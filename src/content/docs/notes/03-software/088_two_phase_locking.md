## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **2단계 잠금(Two-Phase Locking, 2PL)**: 잠금 획득과 해제를 성장•축소 단계로 나눠 충돌 직렬 가능성을 보장하는 잠금 기반 동시성 제어 규약이다.
- **잠금 기반 동시성 제어 규약**: 데이터 접근 전에 잠금을 얻고 정해진 단계에 따라 해제하도록 제한하는 규칙이다.
- **갱신 손실(Lost Update)**: 동시 쓰기로 한 트랜잭션의 변경이 덮인 현상이다.
- **비직렬 결과(Non-serializable Result)**: 어떤 순차 실행으로도 설명할 수 없는 결과이다.

</details>

- 정의/개념: **2단계 잠금(2PL)**은 잠금 획득과 해제를 성장•축소 단계로 분리해 충돌 직렬 가능성을 보장하는 **잠금 기반 동시성 제어 규약**이다.
- 배경/필요성: 무순서 동시 쓰기는 **갱신 손실•비직렬 결과**를 유발한다.

#### 한줄 요약

- 잠금을 모으는 동안에는 풀지 않고 하나라도 푼 뒤에는 새 잠금을 받지 않는다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **단계 분리**: 첫 잠금 해제 뒤에는 새 잠금을 얻지 못하게 하는 2PL 원칙이다.
- **직렬 가능성(Serializability)**: 동시 실행 결과가 유효한 순차 실행과 같은 성질이다.
- **교착(Deadlock)**: 트랜잭션이 잠금을 순환 대기하는 상태이다.
- **엄격 제어**: 미커밋 변경 읽기를 막도록 배타 잠금을 거래 종료까지 유지하는 방식이다.

</details>

- **단계 분리**: 첫 해제 뒤 새 잠금 획득 금지이다.
- **직렬 가능성•교착**: 순서를 보장하지만 대기 순환이 발생할 수 있다.
- **엄격 제어**: 종료까지 배타 잠금을 유지한다.

#### 한줄 요약

- 실행 결과의 순서는 맞추지만 서로 자물쇠를 쥔 채 기다리는 교착이 생길 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **잠금 보유자(Lock Holder)**: 현재 자원 잠금을 소유한 트랜잭션이다.
- **잠금 모드(Lock Mode)**: 잠금의 공유 또는 배타 접근 유형이다.
- **잠금 대기열(Lock Wait Queue)**: 자원 잠금을 기다리는 요청 순서이다.
- **첫 잠금 해제 후 새 요청 차단**: 성장 단계에서 축소 단계로 넘어간 뒤 지키는 제약이다.
- **트랜잭션 대기 순환**: 서로의 잠금을 기다리는 간선이 고리를 이뤄 교착이 된 상태이다.
- **교착 피해자(Deadlock Victim)**: 대기 순환을 끊기 위해 비용을 고려해 롤백 대상으로 선택한 트랜잭션이다.
- **잠금 요청•해제**: 잠금 관리자가 접근 권한을 부여하거나 반환받는 동작이다.
- **롤백 대상•비용**: 교착 순환을 끊을 거래와 취소•재실행 부담을 함께 나타낸 판단 정보이다.

</details>

```text
[잠금 관리자]
    |
    +-- [성장•축소 제어]
    |
    +-- [잠금 상태•대기열]
    |
    +-- [대기 그래프]
            |
            +-- [피해자 선정]
```

선의 의미: 잠금 관리자는 단계 규칙과 잠금 상태를 관리하고, 대기 그래프의 교착 순환을 피해자 선정으로 해소한다.

| 구성요소 | 책임 |
|:---|:---|
| 잠금 관리자 | **잠금 요청•해제** 통제 |
| 성장•축소 제어 | **첫 잠금 해제 후 새 요청 차단** |
| 잠금 상태•대기열 | **잠금 보유자**•**잠금 모드**•**잠금 대기열** 추적 |
| 대기 그래프 | **트랜잭션 대기 순환** 탐지 |
| 피해자 선정 | 교착 시 **롤백 대상•비용** 결정 |

#### 한줄 요약

- 잠금 요청과 대기 관계를 관리하고 교착 시 취소 대상을 고른다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **공유 잠금(Shared Lock, S Lock)**: 여러 트랜잭션의 동시 읽기를 허용하는 잠금이다.
- **배타 잠금(Exclusive Lock, X Lock)**: 다른 트랜잭션의 읽기와 쓰기를 배제하는 잠금이다.
- **잠금 호환성(Lock Compatibility)**: 기존 잠금과 새 잠금의 동시 허용 여부이다.
- **성장 단계(Growing Phase)**: 잠금을 얻되 해제하지 않는 구간이다.
- **축소 단계(Shrinking Phase)**: 잠금을 해제하되 새로 얻지 않는 구간이다.
- **대기 그래프(Wait-for Graph)**: 트랜잭션 간 잠금 대기를 나타낸 그래프이다.
- **잠금 호환성 판정**: 기존 잠금 모드와 요청 모드가 함께 허용되는지 검사하는 동작이다.
- **잠금 획득•연산**: 성장 단계에서 잠금을 추가하고 보호된 데이터 작업을 수행하는 동작이다.
- **대기 등록•교착 판정**: 충돌 요청을 대기 그래프에 기록하고 순환 여부를 검사하는 동작이다.
- **보유 잠금 해제**: 축소 단계에서 소유한 잠금을 반환하는 동작이다.

</details>

```text
잠금 요청
    |
    v
성장 단계
    |
    v
1. 잠금 호환성 판정
    |
    +-- 호환 --> 2. 잠금 획득•연산
    |                   |
    |                   +-- 다음 요청 --> 1. 재판정
    |
    +-- 충돌 --> 3. 대기 등록•교착 판정
                        |
                        +-- 해소 --> 1. 재판정
    |
    | 첫 잠금 해제 또는 트랜잭션 종료
    v
축소 단계
    |
    v
4. 보유 잠금 해제
    |
    +-- 새 잠금 요청 --> 거부
    |
    v
커밋 또는 롤백
```

### 동작 원리

- **1. 잠금 호환성 판정**: **잠금 호환성 판정**으로 **공유 잠금**과 **배타 잠금**의 요청 모드를 비교한다.
- **2. 잠금 획득•연산**: **성장 단계**에서 **잠금 획득•연산**을 수행한다.
- **3. 대기 등록•교착 판정**: **대기 그래프**에 요청을 기록하고 **대기 등록•교착 판정**을 수행한다.
- **4. 보유 잠금 해제**: **축소 단계**에서 **보유 잠금 해제**를 수행한다.

> 요약: 성장 단계에서 잠금을 모으고 축소 단계에서만 해제하며 교착은 탐지•취소로 해소가 핵심이다.

#### 한줄 요약

- 물건을 담는 동안에는 빼지 않고 하나를 빼기 시작하면 새 물건을 담지 않는다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **기본 2단계 잠금**: 축소 단계에서 잠금을 조기 해제할 수 있는 2PL 방식이다.
- **엄격한 2단계 잠금**: 모든 배타 잠금을 커밋•롤백까지 유지해 연쇄 롤백을 막는 방식이다.

</details>

| 잠금 해제 관점 | 기본 2단계 잠금 | 엄격한 2단계 잠금 |
|:---|:---|:---|
| 적용 기준 | 조기 해제•복구 통제 가능 | 연쇄 롤백 방지 우선 |
| 핵심 특징 | **기본 2단계 잠금**은 축소 단계에서 잠금 해제 | **엄격한 2단계 잠금**은 종료까지 배타 잠금 유지 |
| 한계 | 연쇄 롤백 위험 | 잠금 유지•대기 지연 증가 |

> 요약: 해제 시점으로 일반•엄격 제어를 구분한다.

#### 한줄 요약

- 기본 방식은 축소 단계에서 잠금을 풀고 엄격한 방식은 쓰기 잠금을 종료까지 유지한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **전역 잠금 순서**: 모든 거래가 자원을 같은 순서로 잠가 대기 순환을 줄이는 규칙이다.
- **행 단위 잠금(Row-level Locking)**: 필요한 행에만 잠금을 거는 방식이다.
- **키 범위 잠금(Key-range Lock)**: 조건 범위의 키 삽입과 변경을 보호하는 잠금이다.
- **느린 I/O 분리(Slow-I/O Isolation)**: 지연 작업을 트랜잭션 밖으로 옮기는 방식이다.
- **거래 경계 축소(Transaction-boundary Reduction)**: 잠금 보유 시간을 줄이도록 거래 범위를 줄이는 방식이다.
- **멱등성(Idempotency)**: 교착 재시도의 중복 효과를 막는 성질이다.
- **제한 재시도(Bounded Retry)**: 교착 작업을 정한 횟수 안에서 다시 수행하는 방식이다.
- **백오프(Backoff)**: 교착 작업의 재시도 간격을 늘리는 방식이다.
- **트랜잭션 나이(Transaction Age)**: 피해자 선정에 사용하는 거래 경과시간이다.
- **재시도 횟수(Retry Count)**: 같은 거래가 피해자로 선택된 누적 횟수이다.
- **피해자 비용(Victim Cost)**: 거래 취소와 재실행에 필요한 작업량을 나타낸 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 트랜잭션마다 자원 잠금 순서가 달라 대기 순환 | **전역 잠금 순서** 표준화 | 교착 발생 감소 |
| 넓은 범위를 잠가 무관한 거래까지 대기 | **행 단위 잠금**•**키 범위 잠금** 적용 | 불필요한 대기 감소 |
| 외부 I/O 동안 잠금을 유지해 경합 시간 증가 | **느린 I/O 분리**•**거래 경계 축소** | 잠금 유지시간 단축 |
| 교착 피해자 재시도가 없어 일시 충돌을 사용자 노출 | **멱등성**•**제한 재시도**•**백오프** 적용 | 피해자 취소 자동 복구 |
| 같은 거래를 반복 피해자로 골라 기아 발생 | **트랜잭션 나이**•**피해자 비용**•**재시도 횟수** 반영 | 반복 피해자 선정 방지 |

> 적용 사례: 이체는 계좌 번호순으로 잠그고 교착 피해자 트랜잭션을 멱등 재시도

#### 한줄 요약

- 모든 이체가 계좌 번호순으로 잠그면 반대 순서 대기로 생기는 교착을 줄일 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **2단계 잠금 방식 선택 기준**: 연쇄 롤백 방지 필요와 조기 해제 및 복구 통제 능력을 함께 평가하는 기준이다.

</details>

- **2단계 잠금 방식 선택 기준**에 따라 연쇄 롤백 방지는 **엄격한 2단계 잠금**, 조기 해제•복구 통제는 **기본 2단계 잠금**을 선택한다.

#### 한줄 요약

- **2단계 잠금 방식 선택 기준**은 올바른 실행 순서와 교착•대기 비용을 함께 고려한다.
