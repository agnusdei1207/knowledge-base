## 미리 알고가기

- **2단계 잠금(Two-Phase Locking, 2PL)**: 잠금 획득과 해제를 성장·축소 단계로 분리해 직렬 가능성을 보장하는 프로토콜임
- **성장 단계(Growing Phase)**: 트랜잭션이 새로운 잠금을 획득할 수만 있고, 이미 획득한 잠금은 절대 해제할 수 없는 단계임
- **축소 단계(Shrinking Phase)**: 트랜잭션이 잠금을 해제할 수만 있고, 새로운 잠금을 획득하는 것은 절대 불가능한 단계임
- **공유 잠금(Shared Lock, S-Lock)**: 데이터 조회 시 설정하여 일관성을 지키고, 다른 공유 잠금과는 동시 획득이 가능하나 배타 잠금과는 충돌함
- **배타 잠금(Exclusive Lock, X-Lock)**: 데이터 수정 시 설정하여 다른 모든 공유/배타 잠금과의 동시 접근을 차단함
- **교착 상태(Deadlock)**: 둘 이상의 트랜잭션이 서로 보유한 잠금을 기다려 진행하지 못하는 상태임
- **잠금 관리자(Lock Manager)**: 자원별 잠금 보유자와 대기 요청을 기록하고 허용 여부를 판정하는 구성요소임
- **대기 그래프(Wait-For Graph)**: 어떤 트랜잭션이 누구의 잠금을 기다리는지 방향 간선으로 나타낸 그래프임
- **잠금점(Lock Point)**: 성장 단계에서 마지막 잠금을 획득한 시점임
- **연쇄 롤백(Cascading Rollback)**: 취소될 미커밋 값을 읽은 다른 트랜잭션까지 차례로 취소되는 현상임
- **낙관적 동시성 제어(Optimistic Concurrency Control)**: 충돌이 드물다고 보고 먼저 실행한 뒤 커밋 전에 충돌을 검증하는 방식임

## Ⅰ. 개요

- 정의/개념: 잠금 획득과 해제 단계를 분리함
- **배경/필요성**: 동시 쓰기 충돌로 직렬 가능 잠금 규칙 필요

### 쉽게 이해하기 (학습용)
- 필요한 잠금을 모으는 동안에는 해제하지 않고 하나라도 해제한 뒤에는 새 잠금을 받지 않음

## Ⅱ. 특징

- 잠금 해제 뒤에는 새 잠금을 얻지 못한다.
- 직렬성은 보장하지만 교착을 일으킬 수 있다.
- 엄격 제어는 종료까지 배타 잠금을 유지한다.
- 잠금 단위가 관리 비용과 동시 처리량을 좌우한다.

### 쉽게 이해하기 (학습용)
- 연산 순서는 맞추지만 자물쇠를 다 쥐고 있어 교착 상태가 발생할 수 있음

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 잠금 관리자 | 잠금 테이블로 자원별 보유자와 대기열을 추적함 |
| 성장 단계 제어기 | 잠금 요청만 수락하고 해제는 축소 진입 전까지 차단함 |
| 대기 그래프 | 트랜잭션의 대기 방향을 연결해 순환을 감지함 |
| 중단 대상 선정기 | 교착 발견 시 롤백 비용을 비교해 취소할 트랜잭션을 결정함 |

```text
  잠금제어
      ↓
  성장감시
      ↓
  대기그래프
      ↓
  피해자선정
```

> 요약: 잠금 단계 통제·순환 대기 교착 해소

### 쉽게 이해하기 (학습용)
- 잠금 관리자는 요청을 기록하고 대기 관계에 순환이 생기면 한 트랜잭션을 롤백해 진행을 재개함

## Ⅳ. 원리 및 절차 흐름도

```text
  성장잠금
      ↓
  충돌판정
      ↓
  최대획득
      ↓
  축소해제
      ↓
  트랜잭션종료
```

| 절차 | 설명 |
|:---|:---|
| **성장 단계** | 필요한 잠금을 획득하며 이 단계에서는 해제하지 않음 |
| **충돌·데드락 처리** | 충돌 잠금은 대기하고 순환 시 피해 트랜잭션을 롤백함 |
| **락 포인트 도달** | 마지막 잠금을 획득 후 첫 해제를 하며 축소로 전환함 |
| **축소·종료** | 엄격한 제어는 배타 잠금을 종료 시점까지 유지함 |

> 요약: 잠금을 획득하고 첫 해제 뒤에는 새 잠금 없이 종료함

### 쉽게 이해하기 (학습용)
- 카트에 담기만 하다가 빼놓는 순간부터 쇼핑을 멈추고 직행하는 원리임

## Ⅴ. 종류 및 비교

| 비교축 | 기본 2단계 잠금 | 엄격한 2단계 잠금 |
|:---|:---|:---|
| 핵심 특징 | 축소 단계에 진입하면 임의 해제 가능함 | 트랜잭션 종료 시까지 배타 잠금을 유지함 |
| 복구 영향 | 해제 값을 읽을 수 있어 연쇄 롤백 위험이 있음 | 쓰기 잠금을 유지해 연쇄 롤백을 방지함 |
| 주요 위험 | 취소 시 범위 확산으로 복잡도가 상승함 | 잠금 유지 시간이 길어져 대기 지연이 발생함 |
| 적용 기준 | 조기 해제·복구 통제 가능 | 연쇄 롤백 방지 우선 |

> 요약: 해제 시점으로 일반·엄격 제어 구분

### 쉽게 이해하기 (학습용)
- 기본 방식은 축소 단계에서 잠금을 일찍 풀고 엄격한 방식은 쓰기 잠금을 종료까지 유지해 연쇄 롤백을 방지함

## Ⅵ. 실무 사례

1. 이체 시스템은 잠금 순서를 표준화하고 데드락 재시도를 확인함

### 쉽게 이해하기 (학습용)
- 모든 이체가 계좌 번호순으로 잠그면 서로 반대 순서로 기다리는 교착 상태를 줄일 수 있음

## Ⅶ. 결론

- 잠금 순서와 낙관적 검증을 함께 관리함

### 쉽게 이해하기 (학습용)
- 2PL은 직렬 가능성을 보장하지만 교착과 대기를 만들 수 있으므로 잠금 순서·보유 시간·재시도를 함께 설계해야 함
