## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SCI (Software Carbon Intensity, 소프트웨어 탄소 집약도)**: 소프트웨어 시스템이 실행되며 발생하는 운영 탄소 배출량(O)과 하드웨어 제조 과정에서 비롯된 내재 탄소 배출량(M)의 합을 소프트웨어 기능 단위(R)로 나눈 탄소 효율 표준 지표($\mathrm{SCI} = (O + M) / R$, ISO 21031).
- **탄소 집약적 SW 운영 및 ESG 규제 위험(Carbon Footprint & ESG Regulatory Risk)**: 대규모 클라우드 및 AI 모델 운영 시 소프트웨어 레벨의 비효율로 인한 막대한 전력 소비와 Scope 2·3 탄소 배출 및 탄소 국경세 등 글로벌 규제 대응 실패 위험.

</details>

- 정의/개념: 소프트웨어 기능 단위당 운영 배출량(O)과 내재 배출량(M)을 합산하여 **소프트웨어의 탄소 집약도를 정량 측정하는 ISO 표준** 지표
- 배경/필요성: AI 및 클라우드 데이터센터의 전력 소비 급증으로 인한 **탄소 배출 폭증, ESG 규제 강화 및 소프트웨어 효율 측정 지표 부재 위험** 직면

#### 한줄 요약

- $\mathrm{SCI} = (E \times I + M) / R$ 공식을 통해 소프트웨어의 기능 단위당 탄소 배출량을 정량화하고 탄소 인식 컴퓨팅(Carbon-Aware)을 구현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **운영 탄소 배출량($O = E \times I$)**: 전력 소비량($E$, kWh)과 해당 지역/시간대의 전력망 탄소 집약도($I$, $\text{gCO}_2\text{eq/kWh}$)의 곱.
- **내재 탄소 배출량($M$)**: 서버 및 하드웨어 제조·폐기 과정에서 발생한 탄소를 소프트웨어 사용 기간 및 자원 점유 비율에 따라 할당한 값.

</details>

- 사용자 증가에 따른 총배출량 왜곡을 배제하고 **기능 단위($R$)당 효율로 정규화**
- 신재생에너지 발전량이 높은 시간대/리전으로 워크로드를 이동하는 **탄소 인식 컴퓨팅 지원**
- 전력 소비 감축뿐만 아니라 하드웨어 수명 연장을 유도하는 **내재 탄소($M$) 산정 반영**

#### 한줄 요약

- 소프트웨어 코드 최적화와 탄소 인식 스케줄링을 결합하여 성능 SLO를 유지하며 탄소 배출을 획기적으로 감축

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SCI 4대 핵심 매개변수**: 전력 소비량(E), 탄소 집약도(I), 내재 탄소(M), 기능 단위(R).

</details>

```text
[ 소프트웨어 탄소 집약도(SCI) 측정 모델 및 구성요소 ]

 1. [ 운영 탄소 영역 (Operational Emissions: O = E × I) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • E (Energy): CPU/RAM/네트워크 전력 소비량 (kWh)          │
    │  • I (Carbon Intensity): 전력망 실시간 탄소 계수 (gCO2eq/kWh)│
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 2. [ 내재 탄소 영역 (Embodied Emissions: M) ] ──────────────────┐
    • M = 서버 제조 탄소 × (사용 시간 / 하드웨어 수명) × 자원 점유율│
    └────────────────────────────┬────────────────────────────────┘
                                 │ (O + M 합산)
                                 ▼
 3. [ 기능 단위 정규화 (Functional Unit: R) ] ────────────────────┐
    • R: API 호출 1,000건, 활성 사용자 1시간, 처리 트랜잭션 1건    │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 4. [ SCI 지표 산출 및 평가 (SCI = (E × I + M) / R) ]
```

선의 의미: 운영 전력(E)에 탄소 계수(I)를 곱한 운영 탄소와 제조 내재 탄소(M)를 합산하여 기능 단위(R)로 나눔으로써 최종 SCI를 도출하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 전력 소비량 ($E$) | Scaphandre/Kepler 등을 통해 **CPU, GPU, 메모리의 실제 에너지 소비량(kWh) 측정** |
| 탄소 집약도 ($I$) | ElectricityMaps API를 통해 **해당 리전의 시간대별 발전원별 탄소 배출 계수 제공** |
| 내재 탄소 ($M$) | 서버 장비의 **제조·물류·폐기 탄소 발자국을 서비스 점유 시간/코어 비율로 분할 할당** |
| 기능 단위 ($R$) | API 요청 1,000건 등 **소프트웨어의 실질적 비즈니스 처리량을 정의하여 지표 정규화** |

#### 한줄 요약

- $E$(전력), $I$(탄소계수), $M$(내재탄소), $R$(기능단위) 4대 변수가 결합하여 SCI를 산출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SCI 기반 그린 엔지니어링 5단계**: 측정 경계 설정 $\to$ 텔레메트리 수집 $\to$ SCI 산출 $\to$ SLO 대비 효율 검증 $\to$ 탄소 최적화 배포.

</details>

```text
[ SCI 지수 측정 및 탄소 인식 컴퓨팅 최적화 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 측정 대상 서비스 경계(SUT) 및 R 정의 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. Kepler 기반 전력(E) 및 API 탄소계수(I) 수집
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 수식 기반 SCI = (E × I + M) / R 계산│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 의사결정: SCI 감소 여부 및 SLO 충족 판정
 ├───────────────────┬────────────────────┤
 │ 부적합 (SLO 위반) │ 적합 (SCI↓ & SLO 충족)
 │ • 알고리즘 재설계 │ • 프로덕션 배포    │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 탄소 인식 스케줄러(K8s) 연동 자동화 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 경계 설정: 결제 마이크로서비스를 대상으로 '성공한 결제 1,000건'을 기능 단위($R$)로 고정.
2. 텔레메트리 수집: eBPF 기반 Kepler 도구로 컨테이너 전력 소비($E$)를 측정하고 실시간 전력망 API로 탄소 계수($I$)를 수집.
3. SCI 산출: 기존 버전(Baseline)의 SCI($15.2\,\text{gCO}_2\text{eq/1,000건}$) 대비 신규 최적화 코드의 SCI를 계산.
4. 품질 판정: 신규 버전이 SCI $9.8\,\text{gCO}_2\text{eq}$로 35% 감축되면서도 P99 응답 지연(SLO 200ms)을 충족함을 검증.
5. 배포 자동화: 배치가 가능한 대용량 정산 작업은 탄소 계수가 가장 낮은 심야 저탄소 시간대에 자동 실행되도록 스케줄링.

#### 한줄 요약

- 경계 설정 $\to$ 텔레메트리 수집 $\to$ SCI 계산 $\to$ SLO 검증 $\to$ 탄소 인식 배포의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SCI vs 총 탄소 배출량 vs 단순 전력 소비량**: 기능 단위 정규화 지표(SCI), 절대 배출량(Total), 단순 에너지량(Energy).

</details>

| 구분 | 소프트웨어 탄소 집약도 (SCI: ISO 21031) | 기업 총 탄소 배출량 (Total Emissions) | 전력 소비량 (Energy Consumption) |
|:---|:---|:---|:---|
| **적용 기준** | 소프트웨어 버전 간 탄소 효율 비교 및 그린 리팩토링 | 기업 전사 ESG 공시 및 탄소 배출권 거래제 대응 | 데이터센터 PUE 관리 및 인프라 전기 요금 절감 |
| **핵심 특징** | **기능 단위($R$)당 배출량 정규화, 내재 탄소($M$) 포함** | **Scope 1/2/3 전체 온실가스 절대 총량 ($\text{tCO}_2\text{eq}$)** | **소비된 순수 전력 에너지 절대량 (kWh)** |
| **한계** | 측정 경계(SUT)와 $R$ 정의가 왜곡되면 비교 타당성 저하 | 트래픽 증가로 인한 배출 증가와 SW 비효율 구분 불가 | 전력원(화력 vs 태양광)에 따른 탄소 계수 차이 미반영 |

#### 한줄 요약

- 소프트웨어 코드의 친환경성 평가는 SCI, 기업 공시는 총 배출량, 전기 요금 관리는 전력 소비량을 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **성능 저하의 감축 왜곡 방지**: 코드를 비효율적으로 만들어 응답이 느려짐으로써 초당 처리량이 줄어든 것을 탄소 감축으로 오인하지 않도록 방어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Baseline과 비교 대상 간의 측정 리소스 범위 불일치로 왜곡 | **측정 시스템 경계(SUT) 및 기능 단위($R$)를 사전에 문서화하고 고정** | 측정 객관성 및 비교 신뢰도 100% 확보 |
| 시스템 응답 지연(성능 저하)을 탄소 감축 성공으로 오판 | **응답 시간(P99) 및 가용성 등 'SLO 충족 여부'를 게이트 조건 필수 연계** | 서비스 품질 희생 없는 진정한 그린 SW 구현 |
| 전력망의 시간대별 탄소 계수($I$)를 고정 상수로 처리하여 오차 | **실시간 전력망 탄소 집약도 API(ElectricityMaps) 연동 동적 산정** | 탄소 인식 컴퓨팅의 실질적 감축 달성 |

#### 한줄 요약

- 측정 경계 고정, SLO 게이트 연계, 실시간 탄소 계수 연동을 통해 SCI 측정의 실효성을 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **탄소 인식 소프트웨어 아키텍처(Carbon-Aware Architecture)**: 실시간 탄소 집약도에 따라 워크로드를 저탄소 리전으로 동적 마이그레이션하거나 UI 해상도를 조절하는 미래형 아키텍처.

</details>

- **소프트웨어 그린 엔지니어링 SCI 지수** 기반 AI 및 클라우드 시대의 지속 가능한 지속성을 담보하는 핵심 친환경 소프트웨어 표준이며, SLO를 만족하는 범위 내에서 기능 단위당 탄소 배출량을 지속적으로 낮추는 그린 최적화를 실천해야 함

#### 한줄 요약

- $O = E \times I$와 내재 탄소를 결합한 SCI 지표와 탄소 인식 컴퓨팅을 통해 지속 가능한 친환경 소프트웨어를 완성
