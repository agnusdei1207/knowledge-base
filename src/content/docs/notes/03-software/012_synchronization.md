## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **동기화(Synchronization)**: 여러 프로세스가 동시에 한 데이터를 건드려서 데이터가 박살 나는 걸 막기 위해, 줄을 세우고 순서를 통제하는 기술이다.
- **세마포어(Semaphore)**: "입장권 3장 남았다"처럼 정수 카운터를 두고, 표를 얻은 놈만 들어가고 다 쓰면 표를 반납하는 무소유 화장실 열쇠이다.
- **뮤텍스(Mutex)**: 오직 1명만 들어갈 수 있고, "내가 문 잠갔으니 내가 연다"는 소유권(Ownership) 개념이 확실한 독점 화장실 열쇠이다.
- **모니터(Monitor)**: 락 걸고 푸는 귀찮은 짓을 프로그래밍 언어(Java 등) 차원에서 캡슐화해서, `synchronized` 키워드 하나로 알아서 멱살 잡아주는 고수준 방어막이다.

</details>

- 정의: 여러 스레드가 공유 자원을 동시에 건드려서 데이터가 터지는 걸 막기 위해 임계 구역(Critical Section)의 출입을 멱살 잡고 통제하는 **세마포어·뮤텍스·모니터**
- 배경: 락 없이 변수를 동시에 읽고 수정하면 값이 덮어씌워지는 끔찍한 **경쟁 조건(Race Condition)**이 터지기 때문

#### 한줄 요약

- 데이터가 깨지는 걸 막기 위해 입장권을 나눠주거나(세마포어), 독점 락을 걸거나(뮤텍스), 언어가 알아서 막아주는(모니터) 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 두 놈이 동시에 들어오면 무조건 피를 보는, 소스 코드 내의 가장 민감하고 위험한 지뢰밭(공유 데이터 접근 구간)이다.
- **조건 변수(Condition Variable)**: 모니터 안에서 "아직 조건 안 맞으니까 저기서 자고 있어(wait)" 하고, 조건이 맞으면 "일어나서 일해!(signal)"라고 멱살 잡는 시그널링 객체이다.

</details>

- 남은 입장권 수를 카운팅해서 $N$명이 동시에 들어갈 수 있게 해주는 **세마포어** (단, 소유권 없음).
- 무조건 1명만 들어가고, 잠근 놈이 직접 열어야 하는 확실한 주인의식의 **뮤텍스**.
- 언어 차원에서 락과 **조건 변수(Condition Variable)**를 캡슐화해 줘서 코딩하기 겁나 편한 **모니터**.

#### 한줄 요약

- 인원 제한만 두면 세마포어, 주인이 락을 쥐면 뮤텍스, 언어가 다 해주면 모니터다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **재진입 락(Reentrant Lock)**: 자기가 이미 락을 걸었는데 안에서 또 락을 걸려고 할 때, "너니까 봐준다" 하고 데드락 없이 통과시켜 주는 관대한 뮤텍스이다.

</details>

```text
[ 동기화 프리미티브 십자포화 아키텍처 ]
         [ 대기 큐 (Wait Queue) ]
         (락 못 얻은 놈들 대기실)
                   │
                   ▼
        [ 동기화 프리미티브 ]
   (세마포어 / 뮤텍스 / 모니터 중 1)
                   │
         ┌─────────┴─────────┐
         ▼                   ▼
  [ 입장권 획득! ]    [ 표 없음 (블록) ]
         │
         ▼
    [ 임계 구역 ]
 (위험한 공유 변수 작업)
```

| 구성요소 | 책임 |
|:---|:---|
| **세마포어** ($S$) | 원자적 **$P()$/$V()$** 연산으로 정수 카운터를 올리고 내리면서 여러 명($N$)의 입장을 통제하는 매표소 |
| **뮤텍스** (Mutex) | 1:1 독점 락으로, **소유권(Ownership)**을 쥔 놈만 락을 풀 수 있게 멱살 잡고 통제하는 열쇠 |
| 모니터 입구 큐 | 자바 클래스 같은 모니터에 들어오려는 놈들을 입구에서 무조건 1명만 빼고 다 멈춰 세우는 줄 |
| **조건 변수** (Condition) | 모니터 안에서 "넌 조건 안 맞으니 자라(wait)", "이제 조건 맞으니 일어나라(signal)"를 지시하는 알람 |

#### 한줄 요약

- 프리미티브가 문지기 역할을 해서 입장권을 얻은 놈만 임계 구역에 밀어 넣고, 나머지는 큐에 가둔다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가짜 깨어남(Spurious Wakeup)**: 조건 변수에서 자고 있던 놈이 아무도 안 깨웠는데 OS 버그나 타이밍 이슈로 지 혼자 깜짝 놀라 깨어나는 어이없는 현상이다.

</details>

```text
[ 동기화 임계 구역 진입 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 프리미티브 선택 및 락 요청│
└──────────────┬───────────────┘
               ▼
╔══════════════════════════════╗
║ 2. 획득 조건 뺑뺑이 검사     ║
║   ├─ 티켓 없음 ─▶ [ 큐에서 잠 ]
║   │               │ (누가 깨움)
║   │               └─▶ [ 재검사 ]
║   └─ 티켓 있음 ─▶ (통과!)  ║
╚══════════════╤═══════════════╝
               ▼
┌──────────────────────────────┐
│ 3. 락 획득 및 임계 구역 진입 │
│ (나 혼자 데이터 마음껏 수정) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 작업 끝, 락 반납          │
│ (내가 썼던 티켓 다시 돌려줌) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 자는 놈 깨움 (Signal/V)   │
│ (야! 자리 났어 일어나!)      │
└──────────────────────────────┘
```

### 동작 원리

1. 프리미티브 선택: 1명이면 뮤텍스, N명이면 세마포어, 편하게 짜려면 모니터를 선택하고 들이댐.
2. 획득 조건 검사: 락이나 티켓이 있는지 확인함. 없으면 **대기 큐(Wait Queue)**에 쳐박혀서 잠듦.
3. 권한 획득: 티켓을 얻으면 원자적으로 숫자를 까고 **임계 구역(Critical Section)**에 진입함.
4. 임계 구역 실행: 혼자서 안전하게 공유 데이터를 뜯어고침.
5. 권한 해제 및 깨움: 일 다 보면 락 반납하고 큐에서 자는 놈을 **Signal(V 연산)**로 걷어차서 깨움.

#### 한줄 요약

- 락을 검사해서 없으면 큐에서 자고, 있으면 들어가서 작업한 뒤 나올 때 뒷놈을 깨워준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **경쟁 조건(Race Condition)**: 동기화를 안 해놔서, 두 놈이 동시에 계좌에서 돈을 빼가 잔액이 마이너스가 터져버리는 최악의 버그이다.

</details>

| 비교 항목 | **세마포어** (Semaphore) | **뮤텍스** (Mutex) | **모니터** (Monitor) |
|:---|:---|:---|:---|
| 자원 입장 인원 | $N$개 (입장권 개수만큼 여러 명 가능) | 단 1명 (이진 락) | 단 1명 (객체당 하나의 락) |
| 소유권(Ownership) | **없음** (내가 잠갔는데 남이 풀 수도 있는 무법지대) | **있음** (잠근 놈이 무조건 직접 풀어야 함) | **있음** (언어가 알아서 챙겨 줌) |
| 구현 방식 | 원시적인 $P()$(Wait), $V()$(Signal) 연산 노가다 | Lock / Unlock 함수 노가다 | `synchronized` 키워드 한 줄로 끝 |
| 최고존엄 용도 | DB 커넥션 풀처럼 개수 제한 걸 때 | 단일 변수에 동시 접근하는 거 빡세게 막을 때 | 자바에서 뇌 비우고 안전하게 코딩할 때 |

#### 한줄 요약

- 다수를 받으면 세마포어, 주인이 락을 풀면 뮤텍스, 개발자가 꿀 빨려면 모니터다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스핀락(Spinlock)**: 락 얻으려고 잠들지 않고, "열렸어? 열렸어?" 하고 미친 듯이 무한 루프를 돌며 CPU를 갉아먹는 독종 락이다. (대기 시간이 아주 짧을 때만 씀)

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 개발자가 실수로 세마포어 $P, V$ 연산 순서 꼬아놔서 시스템 전체가 **데드락** 터짐 | 구조화된 잠금을 강제하는 **모니터(Monitor)**로 아예 갈아탐 | 락 누락이나 순서 삑사리 같은 휴먼 에러를 원천 봉쇄함 |
| **가짜 깨어남(Spurious Wakeup)** 때문에 조건도 안 맞는데 지 혼자 깨서 데이터 박살 냄 | 무조건 `while(!condition) { wait(); }` 루프로 재검사하게 코딩함 | 아무리 발작해서 깨어나도 조건 안 맞으면 다시 재워버림 |
| 락 걸고 작업하다가 Exception 터져서 락도 안 풀고 죽어서 시스템 얼어붙음 | 무조건 **`try - finally { unlock(); }`** 패턴으로 멱살 잡고 품 | 에러가 터지든 말든 락은 무조건 뱉게 만들어서 락 고갈 예방 |

#### 한줄 요약

- 실수는 모니터로 막고, 가짜 깨어남은 while 문으로 재우며, 에러 터지면 finally로 락을 토해내게 만들어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동기화 프리미티브 선택 기준(Synchronization Selection Criteria)**: 자원이 몇 개인지, 언어가 챙겨주는지, 락 풀 놈이 정해져 있는지를 따져서 무기를 고르는 잣대이다.

</details>

- **동기화 프리미티브 선택 기준** 원칙에 따라, $N$개 자원엔 **세마포어**, 1:1 락엔 **뮤텍스**, 자바 환경엔 **모니터** 채택 기조 확립함

#### 한줄 요약

- 다중 자원 통제는 세마포어, 독점 통제는 뮤텍스, 객체 지향 환경에선 모니터를 채택한다.
