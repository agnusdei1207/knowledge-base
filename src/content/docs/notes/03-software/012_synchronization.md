## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **동기화(Synchronization)**: 다중 프로세스/스레드가 공유 자원에 접근할 때 실행 순서를 맞추고 상호 배제를 보장하는 기제.
- **상호 배제(Mutual Exclusion)**: 임계 구역에 한 번에 단 하나의 스레드만 진입하도록 강제하는 원칙.

</details>

- 정의/개념: 공유 자원 접근 시 **상호 배제(Mutual Exclusion)** 와 조건 동기화를 보장하는 동기화 메커니즘 프리미티브
- 배경/필요성: 멀티스레드/멀티프로세스 환경에서 비원자적 공유 자원 조작으로 인해 데이터 경쟁(Data Race)과 비결정론적 상태 오염이 발생하는 문제를 극복하고, 임계 구역(Critical Section)의 상호 배제(Mutual Exclusion) 및 조건 신호(Condition Signaling)를 보장하는 세마포어·뮤텍스·모니터 프리미티브를 통해 **공유 데이터의 무결성과 스레드 간 협력적 동기화를 실현**할 필요

#### 한줄 요약
- 세마포어, 뮤텍스, 모니터를 통해 임계 구역의 경쟁 조건을 차단하고 데이터 무결성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 다중 스레드가 동시에 접근하면 데이터 레이스가 발생하는 공유 자원 조작 코드 구간.
- **조건 변수(Condition Variable)**: 특정 조건이 만족될 때까지 스레드를 대기(`wait`)시키고 충족 시 통지(`signal`)하는 동기화 객체.

</details>

- **세마포어(Semaphore)**: 정수 카운터 $S$를 기반으로 $N$개의 자원 동시 접근을 제어하는 신호 체계
- **뮤텍스(Mutex)**: 락을 획득한 스레드만이 락을 해제할 수 있는 **소유권 기반 상호 배제**
- **모니터(Monitor)**: 프로그래밍 언어 차원에서 임계 구역과 **조건 변수(Condition Variable)** 를 캡슐화한 고수준 동기화

#### 한줄 요약
- N개 자원은 세마포어, 1:1 배타 소유는 뮤텍스, 객체 캡슐화는 모니터로 해결한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **P / V 연산**: 세마포어에서 카운터를 원자적으로 감소(`P: wait`)시키고 증가(`V: signal`)시키는 Dijkstra의 원자 연산.

</details>

```text
[동기화 프리미티브 3대 아키텍처]
|-- 세마포어 (Semaphore - 정수 카운터 S 및 대기 큐)
|   |-- P(S) 연산 : S <= 0 이면 대기 큐 블로킹, S > 0 이면 S-- 후 통과
|   `-- V(S) 연산 : S++ 후 대기 큐의 스레드 하나를 Wakeup
|-- 뮤텍스 (Mutex - Lock 변수 및 소유자 Thread ID)
|   |-- Acquire() : 락 점유 및 소유권 획득 (실패 시 Sleep 대기)
|   `-- Release() : 소유자 스레드만 락 해제 가능
`-- 모니터 (Monitor - 객체 수준 동기화 구조)
    |-- 진입 큐 (Entry Queue - synchronized 메소드 진입 대기)
    |-- 임계 구역 메소드 (한 번에 1개 스레드만 실행)
    `-- 조건 변수 큐 (Condition Queue - wait() 블로킹 및 notify() 깨움)
```

선의 의미: 계층 및 프리미티브별 자료구조

| 구성요소 | 책임 |
|:---|:---|
| 세마포어 카운터 ($S$) | 가용 자원 수량을 원자적으로 추적하여 $N$개 동시 진입 허용 |
| 뮤텍스 소유권 | 락 획득 스레드 ID를 기록하여 **소유자만 해제**할 수 있도록 배타성 보장 |
| 모니터 진입 큐 | 객체 내부의 임계 구역 진입 스레드를 단 1개로 직렬화 |
| 조건 변수(Condition) | 자원 상태 조건 미충족 시 `wait()` 대기 및 상태 변경 시 `signal()` 통지 |

#### 한줄 요약
- 세마포어·뮤텍스·모니터는 상호배제라는 같은 목표를 추상화 수준만 달리해 제공하므로, 조건 대기와 락 해제 책임을 언어가 대신 져 주는 정도가 선택 기준이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가짜 깨어남(Spurious Wakeup)**: OS 신호 전달 이상으로 조건이 만족되지 않았음에도 wait 상태에서 깨어나는 현상 (`while` 루프로 방어).

</details>

```text
스레드가 임계 구역 진입 요청 (모니터 메소드 호출)
        │
   모니터 락 획득 (진입 큐에서 1개 스레드 선정)
        │
   비즈니스 처리 조건이 충족되었는가?
   ┌────┴─────┐
  아니오       예
   │             │
모니터 락 반납 후 임계 구역 내 공유 데이터 안전 조작
조건 큐 대기      │
(wait 호출)      타 스레드에 의한 상태 변경 통지
   │             (notifyAll 호출로 대기 스레드 깨움)
   │             │
   │        모니터 락 해제 및 메소드 종료
   │             │
   └─────────────┘ (가짜 깨어남 대비 while 루프로 조건 재검사)
```

#### 한줄 요약
- 조건 검사를 while로 두느냐 if로 두느냐가 허위 기상 시 결과를 가르므로, 재검사 한 줄이 정합성의 실질적 방어선이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **이진 세마포어(Binary Semaphore)**: 카운터 $S$가 0과 1만 갖는 세마포어로, 뮤텍스와 유사하나 소유권이 없어 타 스레드가 V() 가능함.

</details>

| 비교 항목 | 계수 세마포어 (Counting Semaphore) | 뮤텍스 (Mutex) | 모니터 (Monitor) |
|:---|:---|:---|:---|
| 동시 접근 허용 수 | **$N$개 동시 허용** | **단 1개 (상호 배제)** | 단 1개 (객체 단위) |
| 락 소유권 유무 | **소유권 없음 (타 스레드가 V 가능)** | **소유권 보유 (획득자만 해제)** | 소유권 내장 (언어 런타임 제어) |
| 구현 계층 | 커널 / 라이브러리 프리미티브 | 커널 / 라이브러리 프리미티브 | **고수준 프로그래밍 언어 (Java 등)** |
| 주 용도 | 커넥션 풀, 생산자-소비자 버퍼 제어 | 단일 공유 변수/자원 보호 | 객체 지향 동시성 데이터 구조 |

#### 한줄 요약
- N개 자원 계측은 세마포어, 단순 단독 락은 뮤텍스, 객체 지향 동시성은 모니터를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스핀락(Spinlock)**: 락을 얻을 때까지 CPU를 점유하며 루프를 도는 바쁜 대기(Busy-Waiting) 락 (초단기 락에 적합).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 세마포어 P()/V() 순서 역전으로 인한 영구 교착 | 언어 차원의 **모니터(`synchronized`, ReentrantLock)** 로 전환 | 락 누락 및 순서 역전 버그 원천 차단 |
| **가짜 깨어남(Spurious Wakeup)** 으로 조건 미충족 상태 진입 | `while(!condition) { wait(); }` 루프 패턴 필수 적용 | 조건 미충족 상태의 오류 진입 100% 방지 |
| 예외 발생으로 인한 락 미해제 누수 | **`try-finally { lock.unlock(); }`** 블록 표준 강제 | 예외 발생 시에도 락 즉시 반납 보장 |
| 초단기 락에서 문맥 전환 오버헤드 과다 | 커널 어댑티브 뮤텍스(Adaptive Mutex) 및 **스핀락** 적용 | 수 나노초 단위 초고속 락 획득 실현 |

#### 한줄 요약
- 동기화는 정합성을 락 경합과 직렬화 구간으로 사들이는 것이므로, 경합이 낮으면 어댑티브 뮤텍스로 대기 비용을 줄이고 조건 대기는 while 재검사와 try-finally로 해제 누락 위험을 없앤다.

## Ⅶ. 결론

- 동시성 프로그래밍(Concurrent Programming)과 커널 동기화의 **핵심 기본 프리미티브 및 데이터 무결성 표준 기술**로 정립되었으며, 실무에서는 **$N$개 한정 자원 계측에는 세마포어(Connection Pool), 단일 자원 배타 제어에는 뮤텍스(ReentrantLock), 객체 수준 캡슐화 및 조건 동기화에는 모니터(`synchronized`/`wait-notify`), 락 해제 누락 방지를 위한 RAII/`try-finally` 패턴**을 필히 준수

#### 한줄 요약
- 동기화 메커니즘은 상호 배제와 조건 동기화를 적재적소에 결합하여 데이터 레이스를 원천 차단하는 핵심 소프트웨어 기술이다.
