## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **동기화(Synchronization)**: 동시 실행 주체의 공유 자원 접근 순서와 상호 배제를 보장하는 제어 기법이다.
- **경쟁 조건(Race Condition)**: 실행 순서에 따라 공유 상태 결과가 달라지는 상태이다.

</details>
- 정의/개념: **동기화**는 공유 자원의 진입•대기•해제 규칙으로 동시 실행 주체의 접근 순서와 상호 배제를 보장하는 실행 제어 기법이다.
- 배경/필요성: 동시 쓰기를 순서화하지 않으면 **경쟁 조건**으로 공유 상태 불일치가 발생한다.

#### 한줄 요약

- 공유 자원 특성에 맞는 진입•대기•해제 규칙을 선택한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상호 배제(Mutual Exclusion)**: 한 시점에 한 실행 주체만 임계 구역에 진입하도록 제한하는 성질이다.
- **조건 변수(Condition Variable)**: 스레드를 공유 상태 조건에 따라 대기시키고 깨우는 동기화 객체이다.
- **캡슐화(Encapsulation)**: 공유 상태와 메서드•조건 변수를 한 경계에 묶어 직접 접근을 제한하는 설계이다.
- **대기 큐(Wait Queue)**: 조건이 충족되지 않은 스레드를 보관하는 대기열이다.
- **깨움 신호(Wakeup Signal)**: 상태 변경 뒤 조건 재검사를 요청하는 신호이다.

</details>

- **상호 배제**와 순서 제어로 경쟁 조건을 방지한다.
- **대기 큐**와 **깨움 신호**로 자원 미가용 스레드 실행을 조정한다.
- **캡슐화**와 **조건 변수**로 상태 변경과 대기•깨움을 결합한다.

#### 한줄 요약

- **상호 배제**와 대기•깨움으로 경쟁 조건을 방지한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **동기화 프리미티브**: 공유 자원의 접근 허가와 대기 조건을 제어하는 기본 동기화 도구이다.
- **임계 구역(Critical Section)**: 한 번에 제한된 실행 주체만 들어가야 하는 코드 범위이다.

</details>

```text
            [실행 스레드]
                   |
        [동기화 프리미티브] -- [대기 큐]
                   |
              [임계 구역]
                   |
              [공유 자원]
```

선의 의미: 실행 스레드는 동기화 프리미티브를 통해 임계 구역에 진입하거나 대기 큐에 머물며, 임계 구역은 공유 자원에 대한 동시 접근을 제한한다.

| 구성요소 | 책임 |
|:---|:---|
| 실행 스레드 | 공유 자원 접근 요청 |
| 동기화 프리미티브 | 접근 허가•대기 조건 제어 |
| 대기 큐 | 미충족 조건 스레드 보관 |
| 임계 구역 | 동시 실행 제한 코드 범위 |
| 공유 자원 | 보호 대상 상태 제공 |

#### 한줄 요약

- **동기화 프리미티브**가 **대기 큐**와 **임계 구역** 접근을 통제한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **프리미티브 선택**: 허가 수•소유권•상태 조건에 맞는 동기화 도구를 정하는 단계이다.
- **획득 조건 검사**: 허가•잠금•조건을 만족해 진입할 수 있는지 확인하는 단계이다.
- **접근 권한 획득**: 세마포어 허가나 뮤텍스•모니터 잠금을 원자적으로 얻는 단계이다.
- **임계 구역 실행**: 보호된 공유 상태를 읽거나 변경하는 단계이다.
- **권한 해제•깨움**: 허가•잠금을 반환하고 대기 스레드에 재검사 기회를 주는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 공유 자원 접근 요청         │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 프리미티브 선택          │
│ 허가 수·소유권·상태 조건    │
└──────────────┬───────────────┘
               ▼
╔══════════════════════════════╗
║ 반복: 획득 조건 미충족      ║
║ 2. 획득 조건 검사           ║
║   ├─ 미충족 ─▶ 대기 큐      ║
║   │             │ 깨움      ║
║   │             └─▶ 재검사  ║
║   └─ 충족 ───────▶ 반복 종료║
╚══════════════╤═══════════════╝
               ▼
┌──────────────────────────────┐
│ 3. 접근 권한 획득           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 임계 구역 실행           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 권한 해제•깨움           │
└──────────────┬───────────────┘
               ▼
        [접근 결과 반환]
```

### 동작 원리

1. **프리미티브 선택**: 허가 수•소유권•상태 조건으로 결정한다.
2. **획득 조건 검사**: 미충족 시 대기 후 조건을 재검사한다.
3. **접근 권한 획득**: 허가나 잠금을 원자적으로 확보한다.
4. **임계 구역 실행**: 보호된 공유 상태에 접근한다.
5. **권한 해제•깨움**: 권한 반환 후 대기 작업에 통지한다.

#### 한줄 요약

- 획득 실패 시 **획득 조건 검사**를 반복한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **세마포어(Semaphore)**: 정수 허가 수로 동시 접근 수를 제한하는 동기화 도구이다.
- **뮤텍스(Mutual Exclusion, Mutex)**: 획득한 소유자만 해제할 수 있는 단일 잠금이다.
- **모니터(Monitor)**: 공유 상태•메서드•조건 변수를 캡슐화한 동기화 구조이다.

</details>

| 동기화 프리미티브 | 세마포어 | 뮤텍스 | 모니터 |
|:---|:---|:---|:---|
| 적용 기준 | 동시 사용 수 제한 | 단일 소유권 잠금 | 상태•조건 **캡슐화** |
| 핵심 특징 | 정수 허가 수•소유권 없음 | 단일 소유자의 잠금•해제 | 상태•**조건 변수** 결합 |
| 한계 | 허가 누락•과다 반환 | 교착•소유자 정지 | 조건 신호 누락 |

> 요약: 동시 허가 수는 **세마포어**, 단일 소유권은 **뮤텍스**, 상태 조건은 모니터가 핵심이다.

#### 한줄 요약

- 허가 수는 세마포어, 소유권은 뮤텍스, 상태 조건은 모니터가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **교착상태(Deadlock)**: 여러 실행 주체가 서로 보유한 잠금 해제를 기다려 모두 진행하지 못하는 상태이다.
- **꼬리 지연(Tail Latency)**: 요청 지연 분포에서 가장 느린 일부 요청의 지연이다.
- **예외 안전 해제(Exception-safe Release)**: 오류가 발생해도 잠금이나 허가를 반드시 반환하는 처리 방식이다.
- **전역 잠금 순서(Global Lock Ordering)**: 모든 실행 경로가 여러 잠금을 같은 순서로 획득해 환형 대기를 막는 규칙이다.
- **락 분할(Lock Striping)**: 하나의 큰 잠금을 여러 독립 잠금으로 나눠 서로 다른 데이터 접근의 경합을 줄이는 기법이다.
- **허가 누수(Permit Leak)**: 세마포어 허가를 잘못 반환하거나 회수하지 않아 실제 사용량과 허가 수가 어긋나는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잠금 획득 순서가 달라 **교착상태** 발생 | **전역 잠금 순서**와 대기시간 제한 적용 | 환형 대기 예방 |
| **임계 구역**이 길어 경합•**꼬리 지연** 증가 | 임계 구역 축소와 **락 분할** 및 보유시간 계측 | 동시 실행 범위 확대 |
| 조건 신호 유실•허위 깨움으로 상태 오류 | 조건 반복 검사와 동일 락 신호 보호 | 정확한 대기•재개 조건 유지 |
| 세마포어 과다 반환•뮤텍스 비소유 해제로 **허가 누수** | 소유권 검사와 **예외 안전 해제** | 허가•잠금 상태 일관성 유지 |

#### 한줄 요약

- 잠금 순서•보유시간•**예외 안전 해제**를 검증한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **허가 수**: 동시 접근 수가 여러 개면 세마포어를 고르는 기준이다.
- **소유권**: 잠금 해제 주체가 정해지면 뮤텍스를 고르는 기준이다.
- **상태 조건**: 공유 상태 대기가 필요하면 모니터를 고르는 기준이다.
- **동기화 도구 선택 기준**: 허가 수와 잠금 소유권 및 상태 조건에 맞는 프리미티브를 고르는 기준이다.

</details>

- **동기화 도구 선택 기준**에 따라 **허가 수**가 여러 개면 **세마포어**, 단일 **소유권**이면 **뮤텍스**, 공유 **상태 조건** 대기이면 **모니터**를 선택한다.

#### 한줄 요약

- 허가 수•소유권•상태 조건에 맞는 프리미티브를 선택한다.
