## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **상호 배제 및 조건 동기화(Mutex & Condition Sync)**: 단일 스레드만 임계 구역에 진입하도록 보장하고(뮤텍스/세마포어), 특정 상태 조건이 충족될 때까지 대기시키는 동기화 기법.
- **경쟁 조건 및 데이터 붕괴(Race Condition & Inconsistency)**: 두 개 이상의 스레드가 공유 변수를 비원자적으로 동시 수정할 때 연산 순서에 따라 데이터가 오염되는 현상.

</details>

- 정의/개념: 다중 스레드 환경에서 공유 자원 접근 시 **상호 배제(Mutual Exclusion)와 조건 동기화** 활용 보장하는 동기화 메커니즘 체계
- 배경/필요성: 비원자적 공유 변수 갱신 시 발생하는 경쟁 조건(Race Condition) 방지 및 데이터 일관성 보장 필요

#### 한줄 요약

- 공유 자원의 경쟁 조건을 방지하기 위해 임계 구역 진입을 원자적으로 제어하는 세마포어·뮤텍스·모니터 프리미티브

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 복수의 스레드가 동시에 진입하면 데이터 불일관이 발생하는 공유 자원 접근 코드 구간.
- **조건 변수(Condition Variable)**: 모니터 내에서 특정 조건이 충족될 때까지 스레드를 대기(wait)시키고 조건 충족 시 깨우는(signal) 시그널링 객체.

</details>

- **세마포어**: 정수 카운터 S로 N개 동시 진입을 허용하는 계수형 상호 배제 (소유권 없음)
- **뮤텍스**: 단일 스레드 진입을 허용하고 잠금 획득 스레드가 해제 권한을 독점하는 소유권 기반 상호 배제
- **모니터**: 잠금과 **조건 변수** 활용 언어 차원에서 캡슐화하여 임계 구역을 객체 단위로 보호

#### 한줄 요약

- N개 자원 계수는 세마포어, 소유권 기반 단일 잠금은 뮤텍스, 언어 수준 캡슐화는 모니터

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **재진입 잠금(Reentrant Lock)**: 이미 잠금을 보유한 스레드가 동일 잠금을 재획득할 때 교착 상태 없이 허용하는 잠금 기법.

</details>

```text
[ 동기화 프리미티브 구조 ]
대기 큐 (Wait Queue)
└─ 잠금 획득 대기 스레드 보관
동기화 프리미티브
├─ 세마포어: 카운터 S, P() = wait, V() = signal
├─ 뮤텍스: 소유 스레드 ID·Lock/Unlock
└─ 모니터: 진입 큐 + 조건 변수(wait/signal)
임계 구역 (Critical Section)
└─ 잠금 보유 스레드만 공유 자원 접근 허용
```

선의 의미: 가지(`├─`, `└─`)는 동기화 프리미티브의 구성 및 임계 구역 보호 관계

| 구성요소 | 책임 |
|:---|:---|
| 세마포어 (S) | **P()/V()** 원자 연산으로 N개 동시 접근 허용 |
| 뮤텍스 | **소유권** 기반 1:1 잠금·해제 통제 |
| 모니터 진입 큐 | 객체 단위 단일 스레드 진입 보장 |
| 조건 변수 | 조건 미충족 시 **wait**, 충족 시 **signal** 기반 스레드 제어 |

#### 한줄 요약

- 프리미티브가 대기 큐와 카운터·소유권을 관리하여 임계 구역에 대한 배타적 접근을 보장

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가짜 깨어남(Spurious Wakeup)**: 조건 변수의 wait 상태에서 signal 없이 운영체제 내부 이벤트로 스레드가 깨어나는 현상으로, 조건 재검사 루프로 대응.

</details>

```text
임계 구역 진입 요청
   │
   ▼
1. 잠금 획득 가능 여부 확인
├─ 가능: 원자적 잠금 획득 → 임계 구역 진입
└─ 불가: 대기 큐 진입 (블로킹)
         │
         ▼
      2. 신호(Signal/V()) 수신 시 재확인
         └─ 가짜 깨어남 대비 while 루프 재검사
   │
   ▼
3. 임계 구역 실행 (공유 자원 안전 접근)
   │
   ▼
4. 잠금 해제 (Unlock/V())
   └─ 대기 큐 스레드에 신호 전달
```

**동작 원리** 1. **잠금 획득 확인**: 세마포어 카운터·뮤텍스 소유 여부를 원자적으로 확인하여 획득 가능 시 즉시 진입
2. **대기 블로킹**: 획득 불가 시 대기 큐에 진입하여 블록킹, signal 수신 후 `while` 루프로 조건 재검사
3. **임계 구역 실행**: 잠금 보유 상태에서 공유 자원을 안전하게 접근
4. **잠금 해제**: Unlock/V() 연산으로 잠금을 해제하고 대기 큐의 다음 스레드에 신호 전달

#### 한줄 요약

- 잠금 확인·획득·임계 구역 실행·해제·신호 전달의 원자적 순환으로 상호 배제 보장

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **경쟁 조건(Race Condition)**: 동기화 없이 복수 스레드가 공유 변수를 동시 읽기·수정할 때 실행 순서에 따라 결과가 달라지는 비결정적 버그.

</details>

| 구분 | 세마포어 (Semaphore) | 뮤텍스 (Mutex) | 모니터 (Monitor) |
|:---|:---|:---|:---|
| 적용 기준 | N개 자원 동시 접근 제한 필요 시 | 단일 자원 1:1 소유권 잠금 필요 시 | 객체 지향 언어에서 편리한 캡슐화 필요 시 |
| 핵심 특징 | 계수 카운터 S·**P()/V()** 원자 연산 | **소유권** 기반 Lock/Unlock, 보유자만 해제 | `synchronized` 기반 자동 잠금·**조건 변수** 내장 |
| 한계 | 소유권 없어 타 스레드 해제 가능 (시그널 누락) | 단일 잠금만 지원, 재진입 시 **교착 상태** 주의 | 언어 런타임 의존성·모니터 내부 경합 발생 |

#### 한줄 요약

- N개 자원 계수 제어는 세마포어, 소유권 기반 단독 잠금은 뮤텍스, 언어 수준 캡슐화는 모니터 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스핀락(Spinlock)**: 잠금 획득 전까지 CPU를 점유하며 반복 확인하는 바쁜 대기 방식으로, 잠금 대기 시간이 문맥 전환 비용보다 짧을 때 사용.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| P()/V() 순서 오류로 **교착 상태** 발생 | **모니터** 기반 구조화 잠금으로 전환 | 잠금 누락·순서 오류 기반 교착 상태 예방 |
| **가짜 깨어남** 기반 조건 미충족 상태에서 임계 구역 진입 | `while(!condition) { wait(); }` 루프로 조건 재검사 | 가짜 깨어남 후 조건 미충족 진입 차단 |
| 예외 발생 시 잠금 미해제로 **잠금 고갈** 발생 | `try-finally { unlock(); }` 패턴 강제 적용 | 예외 발생 여부와 무관한 잠금 해제 보장 |

#### 한줄 요약

- 순서 오류는 모니터로, 가짜 깨어남은 while 재검사로, 예외 잠금 미해제는 try-finally로 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동기화 프리미티브 선택 기준**: 동시 접근 허용 수(N)·소유권 필요 여부·언어 지원 수준에 따라 세마포어·뮤텍스·모니터를 결정하는 판단 기준.

</details>

- N개 자원 접근 제어는 **세마포어**, 단일 자원 소유권 잠금은 **뮤텍스**, 언어 차원 캡슐화는 **모니터** 선택

#### 한줄 요약

- 자원 수·소유권 요구·언어 환경에 따라 세마포어·뮤텍스·모니터를 선택하여 경쟁 조건을 방지
