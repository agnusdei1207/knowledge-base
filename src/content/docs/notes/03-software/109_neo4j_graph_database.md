## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Property Graph 및 무색인 인접성(Index-Free Adjacency)**: 노드(Node), 관계(Relationship), 속성(Property)으로 데이터를 표현하며, 각 노드가 이웃 노드의 물리적 메모리 포인터를 직접 소유하여 $O(1)$ 속도로 관계를 순회하는 그래프 모델.
- **다단계 Recursive JOIN 병목(Recursive Join Bottleneck)**: RDBMS에서 3-Hop 이상의 친구의 친구나 이상거래 탐색 시 조인 테이블의 기하급수적 인덱스 탐색 비용으로 인해 쿼리가 멈추는 한계.

</details>

- 정의/개념: 복잡한 네트워크 관계를 표현하기 위해 **노드(Node), 관계(Edge), 속성(Property) 및 무색인 인접성(Index-Free Adjacency)** 을 제공하는 그래프 NoSQL
- 배경/필요성: 소셜 네트워크 및 추천 시스템에서 RDBMS의 다단계 Recursive JOIN 수행 시 발생하는 **기하급수적 인덱스 탐색 비용 및 성능 급락 위험** 직면

#### 한줄 요약

- 노드 간 직접 포인터 연결(무색인 인접성)과 Cypher 질의어를 통해 다단계 복합 관계를 $O(1)$ 복잡도로 순회

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **무색인 인접성(Index-Free Adjacency)**: 조인 인덱스 탐색($O(\log N)$) 없이 각 노드의 인접 포인터를 쫓아 바로 다음 노드로 이동($O(1)$)하는 그래프 엔진 특성.
- **Cypher 질의어**: `MATCH (u:User)-[:FRIEND]->(f:User) RETURN f`와 같이 아스키 아트 형태로 노드와 관계를 직관적으로 서술하는 선언적 질의 언어.

</details>

- 인덱스 룩업 없이 메모리 포인터로 관계를 횡단하는 **무색인 인접성(Index-Free Adjacency)**
- 노드와 관계 모두에 동적 키-값 속성을 부여하는 **Property Graph 모델 지원**
- 그래프 전용 선언적 질의어인 **Cypher 언어 및 100% Strict ACID 트랜잭션 완비** #### 한줄 요약

- 무색인 인접성과 Cypher 언어로 복잡한 다단계 관계를 직관적이고 고속으로 탐색

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Property Graph 4대 구성요소**: Node(개체), Relationship(방향성 연결), Label(노드 분류), Property(키-값 속성).

</details>

```text
[ Neo4j Property Graph 모델 아키텍처 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                        Neo4j Property Graph Model                      │
 ├────────────────────────────────────────────────────────────────────────┤
 │ (User:Alice {age:30}) ───[:KNOWS {since:2026}]───► (User:Bob {age:28}) │
 │   ▲                      ▲                           ▲                 │
 │   [Node A & Label]       [Relationship & Property]   [Node B & Label]  │
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 노드와 노드가 방향성과 속성을 가진 관계로 직접 메모리 포인터 바인딩되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 노드 (Node) | 사용자, 상품, 계좌 등 비즈니스 실체와 **식별자 및 Label 분류 정보 표현** |
| 관계 (Relationship) | 노드 간의 의미 있는 연결을 **방향성(Directed)과 유형(Type)으로 직접 포인터 연결** |
| 속성 (Property) | 노드 및 관계에 유연하게 부착되는 **키-값(Key-Value) 형태의 부가 메타데이터 저장** |
| 레이블 (Label) | 노드의 역할을 그룹화하고 **Cypher 탐색 시 시작점 인덱싱 범위 한정** |

#### 한줄 요약

- 노드, 관계, 속성, 레이블의 4대 요소로 현실 세계의 복잡한 연결망을 직관적으로 모델링

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **그래프 순회(Graph Traversal) 5단계**: 시작 노드 인덱스 탐색 $\to$ 관계 유형 필터링 $\to$ 인접 노드 포인터 순회 $\to$ 깊이(Hop) 제한 판정 $\to$ 경로 결과 반환.

</details>

```text
[ Cypher 그래프 질의 처리 및 순회 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 시작 노드 탐색: Label/Index 기반   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 관계 유형 및 방향 필터링 (:KNOWS)   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 인접 관계 순회: 메모리 포인터 이동 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 깊이 판정: 최대 Hop (1.3) 검증     │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 최적 경로 및 연관 서브그래프 반환   │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 시작점 탐색: 인덱스를 통해 Cypher 쿼리의 출발점 노드(예: `Alice`)를 $O(\log N)$으로 탐색.
2. 관계 필터링: 지정된 관계 유형(`:FRIEND`)과 방향성에 부합하는 포인터 링크만 필터링.
3. 인접 노드 순회: 인덱스 없이 노드가 직접 가지고 있는 메모리 주소 포인터를 따라 이웃 노드로 $O(1)$ 즉시 이동.
4. 깊이 판정: 지정된 N-Hop(예: 3단계 이내) 범위에 도달했는지 확인하며 그래프 확장을 통제.
5. 결과 반환: 조건에 일치하는 모든 경로와 노드 집합을 추출하여 클라이언트에 반환.

#### 한줄 요약

- 출발 노드 인덱스 검색 $\to$ 관계 필터링 $\to$ 포인터 순회 $\to$ Hop 검증 $\to$ 경로 반환의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RDBMS vs Neo4j**: 조인 테이블로 관계를 연결하는 2차원 테이블 모델과 물리 포인터로 연결된 Property Graph 모델.

</details>

| 구분 | RDBMS (관계형 데이터베이스) | Neo4j (그래프 데이터베이스) |
|:---|:---|:---|
| **적용 기준** | 정형 데이터 집계, 회계 장부, 트랜잭션 중심 | 이상금융거래 탐지(FDS), 지식 그래프(RAG), 소셜망 |
| **핵심 특징** | **외래키(FK) 및 조인 테이블 기반 다단계 조인 연산** | **무색인 인접성(Index-Free Adjacency) 기반 포인터 순회** |
| **한계** | 3-Hop 이상 조인 시 기하급수적 성능 저하 및 타임아웃 | 전체 테이블 스캔 집계(`SUM, AVG`) 및 수평 샤딩 난이도 |

#### 한줄 요약

- 정형 수치 집계는 RDBMS, 복잡한 네트워크 관계 탐색은 Neo4j를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **슈퍼 노드 문제(Super Node Problem)**: 인플루언서처럼 단일 노드에 수백만 개의 엣지가 연결되어 있어 순회 시 메모리가 폭증하고 성능이 급락하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수백만 엣지가 연결된 Super Node 탐색 시 메모리 폭증 | **Super Node 서브 노드 분할 및 관계 속성 인덱스 필터링** | 탐색 메모리 폭주 방지 및 고속 순회 |
| 시작 노드 인덱스 누락으로 인한 전체 그래프 스캔 | **선택도 높은 Node Label 및 식별자 속성에 Schema Index 생성** | 출발점 탐색 시간 단축 |
| Cypher 쿼리에서 무제한 Hop 순회로 인한 무한 루프 | **반드시 최대 순회 깊이를 명시 (`-[:KNOWS*1.3]->`)** | 쿼리 폭주 차단 및 응답 시간 보장 |

#### 한줄 요약

- Super Node 분할, 시작점 인덱싱, 최대 Hop 제한을 통해 그래프 탐색 성능을 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지식 그래프 및 AI RAG 연계(Knowledge Graph & RAG)**: LLM의 환각(Hallucination)을 방지하기 위해 Neo4j 지식 그래프를 검색 증강에 결합하는 차세대 엔터프라이즈 아키텍처.

</details>

- **Neo4j** 기반 데이터 간의 관계가 가장 중요한 비즈니스 가치인 도메인에서 대체 불가능한 핵심 그래프 데이터베이스이며, 지식 그래프 구축 및 이상금융거래 탐지(FDS) 분야에서 최고의 탐색 성능을 발휘함

#### 한줄 요약

- 무색인 인접성과 Property Graph 모델을 통해 다단계 네트워크 관계를 고속으로 탐색
