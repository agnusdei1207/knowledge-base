## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **피처 플래그(Feature Flag, Feature Toggle)**: 코드 다시 빌드해서 재배포할 필요 없이, 웹 콘솔에서 마우스 딸깍 한 번으로 신기능을 켰다 껐다(ON/OFF) 할 수 있는 궁극의 통제판이다.
- **배포와 릴리스 분리(Decoupling Deployment from Release)**: 코드를 서버에 올리는 건 '배포', 그 코드를 유저한테 보여주는 건 '릴리스'로 분리해서, 일단 배포해놓고 나중에 원할 때 릴리스하는 기적의 마술이다.
- **킬 스위치(Kill Switch)**: 신기능 켰다가 서버 터질 거 같으면, 다급하게 롤백 배포하는 게 아니라 1초 만에 피처 플래그 OFF 버튼 눌러서 기능만 비활성화시키는 긴급 생존 버튼이다.

</details>

- 정의: 재배포 없이 런타임에 특정 기능의 ON/OFF와 타깃 유저군 노출을 동적으로 통제하는 **Feature Flag**
- 배경: 배포와 노출이 한 몸이라 **출시 지연과 장애 복구 지연**이라는 끔찍한 족쇄가 생기기 때문

#### 한줄 요약

- 배포 따로 노출 따로! 코드는 이미 올라가 있고 켤지 말지만 마우스로 딸깍거리는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **타겟팅 및 세그먼테이션(Targeting & Segmentation)**: "강남구 사는 20대 VIP 유저한테만 켜줘"처럼 유저 속성을 팩트 체크해서 핀포인트로 기능을 열어주는 얌체 스킬이다.
- **트렁크 기반 개발(Trunk-Based Development Enabler)**: 미완성된 코드를 메인 브랜치에 쑤셔 넣어도 플래그로 OFF 해두면 아무도 모르니까, 맘 놓고 코드 합치기를 할 수 있게 해주는 방패이다.

</details>

- **배포(Deployment)와 릴리스(Release)의 완벽한 분리**.
- 런타임 제어를 통한 1초 컷 **Kill Switch (긴급 차단)** 및 **Targeting (표적 노출)**.
- **Trunk-Based Development (메인 브랜치 개발)** 촉진 및 **A/B Testing** 기반 간 보기 검증.

#### 한줄 요약

- 배포의 두려움을 없애고(분리), 맘에 드는 놈만 켜주며(타겟팅), 터지면 1초 만에 끈다(킬 스위치).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **런치다클리 / 언리시(LaunchDarkly / Unleash)**: 회사 전체의 피처 플래그 ON/OFF를 중앙 관리하고, 앱한테 "야 VIP한테만 버튼 켜줘라" 쏴주는 1티어 플래그 SaaS/오픈소스이다.

</details>

```text
[ 피처 플래그 십자포화 아키텍처 ]

[ 피처 플래그 중앙 콘솔 (LaunchDarkly) ]
     │ (ON/OFF 룰셋 실시간 갱신)
     ▼
 [ 앱 서버 내부의 플래그 SDK (평가 모듈) ]
     │
┌────┴────┐
▼         ▼
(True)   (False)
신기능    레거시 기능
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **설정 저장소 (Console)** | 기획자나 마케터가 "새 기능 오픈!" 하고 마우스 누르는 중앙 관리소 |
| **평가 모듈 (SDK)** | 룰을 보고 "이 유저는 VIP니까 True 반환!" 하고 0.1초 만에 채점하는 봇 |
| **기능 경로 (If-Else)** | 평가 결과에 따라 신기능(True) 띄울지 헌기능(False) 띄울지 갈라지는 갈림길 |
| **감사 기록 (Audit Log)** | 누가 언제 멀쩡한 플래그 끄고 퇴근해서 장애 냈는지 추적하는 블랙박스 |

#### 한줄 요약

- 콘솔에서 스위치를 누르면 $\to$ SDK가 점수 매겨서 $\to$ 코드가 If문 타고 갈라진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **플래그 평가(Flag Evaluation)**: 앱에 접속한 유저의 ID, 지역을 보고 SDK가 "얘한텐 이 버튼 보여줘야겠다(True)" 하고 머리 굴려서 판단하는 과정이다.

</details>

```text
[ 피처 플래그 런타임 평가 십자포화 흐름 ]
┌──────────────────────────────┐
│ 유저 HTTP 요청 수신          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 유저 컨텍스트 추출        │
│ (ID: 강남VIP, 지역: 서울)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 플래그 룰셋 평가          │
│ ("강남 VIP면 True 줘라")     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 조건문(If-Else) 분기      │
│ (True이므로 신기능 경로 탐)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 평가 결과 기록 및 응답    │
│ (VIP 전용 UI 렌더링 완료!)   │
└──────────────────────────────┘
```

### 동작 원리

1. 문맥 추출: 접속 유저가 무과금인지 VIP인지 스펙(컨텍스트)을 뽑아냄.
2. 규칙 평가: 플래그 SDK가 "VIP한테만 켜주랬지? 넌 True다" 판정함.
3. 안전 기본값: 콘솔 서버 터지면 앱 뻗지 말라고 기본값(False) 던짐.
4. 분기 실행: True면 반짝이는 새 기능, False면 칙칙한 옛날 기능 띄움.
5. 기록: "방금 VIP 1명한테 새 버튼 띄웠음" 통계 서버로 로깅함.

#### 한줄 요약

- 호구 조사(문맥) $\to$ 팩트 체크(평가) $\to$ 차별 대우(분기)의 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **카나리 배포 vs 피처 플래그**: 카나리는 인프라 라우터 단에서 "아무나 5%" 맹목적으로 갈라치는 거고, 피처 플래그는 코드 If문 단에서 "특정 타깃"만 핀포인트로 켜주는 거다.

</details>

| 비교 항목 | **Canary Deployment (인프라 무식 제어)** | **Feature Flag (코드 똑똑 제어)** |
|:---|:---|:---|
| 제어 계층 | L7 문지기 라우터 (Ingress, Istio) | **소프트웨어 애플리케이션 (If문)** |
| 타겟팅 능력 | "아무나 5%만 들어와라" (눈먼 가중치) | **"강남 20대 VIP 3명만 켤게" (정밀 타겟팅)** |
| 스위치 주체 | 콘솔 권한 있는 인프라 아재들 | **개발자, 기획자(PM), 마케터 누구나 딸깍!** |
| 롤백 비용 | 라우팅 비율 롤백 배포 쳐야 함 | **배포 필요 없이 콘솔 스위치 끄면 1초 컷** |

#### 한줄 요약

- 카나리는 서버 단에서 트래픽을 쪼개는 거고, 플래그는 코드 단에서 IF문으로 기능을 쪼개는 거다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **플래그 오염(Flag Pollution)**: 런칭 끝난 기능인데 소스코드에서 If-Else(플래그)를 안 지우고 놔둬서, 코드가 스파게티가 되고 경우의 수가 폭발하는 끔찍한 기술 부채이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 한 번 쓰고 버릴 플래그 안 지워서 코드 개판 됨 | **Flag 만료일(TTL)** 정해두고 끝나면 무조건 삭제 | 스파게티 코드 방지 (플래그 오염 척결) |
| 플래그 콘솔 죽었다고 앱 전체가 하얀 화면 됨 | **로컬 캐시** 쓰고 실패 시 **기본값(Fallback)** 리턴 | 콘솔 죽어도 유저 앱은 평화롭게 돌아감 |
| 플래그 10개 묶여있어서 테스트 경우의 수 폭발함 | **플래그끼리 의존성 묶는 짓 금지** | QA팀 뒷목 잡고 쓰러지는 거 방지 |

#### 한줄 요약

- 다 쓴 플래그는 즉시 쓰레기통에 버리고, 콘솔 죽을 때 대비해서 캐시(기본값) 박아둬라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **피처 플래그 관리 기준(Feature Flag Management Standards)**: 다 쓴 플래그는 제때 치우는지, 오픈 소스 표준(OpenFeature) 지키는지 팩트 체크하는 잣대이다.

</details>

- **피처 플래그 관리 기준** 원칙에 따라, 임시 오픈용 릴리스 플래그는 **만료 즉시 척결**, 비상 차단용 킬 스위치는 **평생 유지** 기조 확립함

#### 한줄 요약

- 배포의 두려움을 0으로 만들고, 마케터에게 릴리스 권한을 쥐여주는 마법의 리모컨이다.
