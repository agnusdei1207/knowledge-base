## 미리 알고가기

- **인메모리 DB(In-Memory Database)**: ‘인메모리 디비’로 읽으며, 주 데이터를 메모리에 저장해 낮은 지연을 제공함
- **TTL(Time To Live)**: ‘티티엘’로 읽고 영문 머리글자를 딴 약어이며, 키가 자동 삭제될 때까지의 시간을 지정함
- **RDB(Redis Database)**: ‘알디비’로 읽고 영문 머리글자를 딴 약어이며, Redis 상태를 시점별 스냅샷 파일로 저장함
- **AOF(Append Only File)**: ‘에이오에프’로 읽고 영문 머리글자를 딴 약어이며, 변경 명령을 순서대로 기록해 복구함
- **센티널 (Sentinel)**: 장애를 감지해 주 복제본을 승격함
- **Redis 클러스터 (Redis Cluster)**: 해시 슬롯으로 키를 분산함
- **제거 정책 (Eviction Policy)**: 메모리 부족 시 삭제할 키를 정함
- **원자 명령(Atomic Command)**: 다른 명령이 중간에 끼어들지 않은 것처럼 한 단위로 실행되는 명령임
- **영속성(Persistence)**: 메모리 값을 디스크 기록으로 남겨 재시작 뒤 복구할 수 있게 하는 성질임
- **해시 슬롯(Hash Slot)**: 키의 해시값을 기준으로 Redis 클러스터 노드에 분배하는 논리 구간임
- **핫키(Hot Key)**: 요청이 한 키에 과도하게 집중되어 담당 노드의 병목을 만드는 키임
- **캐시 스탬피드(Cache Stampede)**: 인기 키가 만료될 때 많은 요청이 동시에 원본 저장소로 몰리는 현상임
- **멤캐시드(Memcached)**: 단순 키값 객체를 메모리에 임시 저장하는 분산 캐시임

## Ⅰ. 개요

- **정의/개념**: 메모리에서 **키 기반 자료구조**를 처리하는 저장소
- **기존 한계**: 디스크 반복 접근으로 **실시간 처리 지연** 증가

### 쉽게 이해하기 (학습용)
- 디스크 창고 대신 메모리 책상에서 다양한 자료형을 바로 계산하는 키값 저장소임

## Ⅱ. 특징

- 메모리에서 **자료구조별 원자 명령** 수행
- TTL·제거 정책으로 **메모리 한도 관리**
- RDB·AOF 정책이 **복구 범위·쓰기 비용** 결정

### 쉽게 이해하기 (학습용)
- 빠르지만 메모리 한도와 재시작 복구 및 주 노드 장애를 함께 설계해야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 키·자료구조 | 자료형별 원자 명령을 수행함 |
| TTL·제거 정책 | 키 수명과 메모리 삭제 대상을 정함 |
| RDB·AOF | 스냅샷과 로그로 복구 범위를 정함 |
| 복제·센티널 | 변경 복제와 장애 승격을 수행함 |
| Redis 클러스터 | 해시 슬롯과 담당 노드를 연결함 |

```text
  키값할당
      ↓
  원자연산
      ↓
  수명제거
      ↓
  지속복제
```

> 요약: 해시 슬롯의 원자 명령을 영속성과 복제에 반영함

### 쉽게 이해하기 (학습용)
- 키 자료형과 수명 및 영속성과 복제가 메모리 데이터를 관리함

## Ⅳ. 원리 및 절차 흐름도

```text
  명령수신
      ↓
  슬롯확인
      ↓
  명령실행
      ↓
  변경반영
      ↓
  결과반환
```

| 절차 | 설명 |
|:---|:---|
| 명령수신 | 키와 자료형 명령을 수신함 |
| 슬롯확인 | 해시 슬롯의 담당 노드를 판정함 |
| 명령실행 | 메모리 값과 수명을 원자 갱신함 |
| 변경반영 | AOF 기록과 복제를 수행함 |
| 결과반환 | 실행 결과나 이동 정보를 반환함 |

> 요약: 담당 노드가 원자 명령을 복제 경로에 반영함

### 쉽게 이해하기 (학습용)
- 담당 슬롯에서 원자 명령을 실행하고 복제본에 남김

## Ⅴ. 종류 및 비교

| 인메모리 저장소 | Redis | Memcached |
|:---|:---|:---|
| 적용 기준 | 자료형 연산·**복구 필요** | 단순 객체의 **임시 캐시** |
| 핵심 특징 | 다양한 자료형·**영속성 지원** | 단순 키값·**분산 캐시** |
| 한계 | 메모리 비용·**복제 정책 복잡도** | 자료형 제한·**영속성 부재** |

> 요약: Redis는 자료형·복구, 단순 캐시는 조회 중심

### 쉽게 이해하기 (학습용)
- 전자는 자료형과 복구에 맞고 후자는 단순 캐시에 맞음

## Ⅵ. 실무 사례

1. 응답 캐시에 **TTL 분산** 적용
2. 세션 저장소에 **AOF 복구** 적용

### 쉽게 이해하기 (학습용)
- 캐시 키의 TTL을 분산하면 인기 데이터가 한꺼번에 만료되어 원본 저장소로 요청이 몰리는 현상을 줄일 수 있음
- 세션 저장소는 AOF 복구 범위와 주 복제본 승격 시간을 검증해 재시작과 장애 때의 손실 범위를 통제함

## Ⅶ. 결론

- 임시 캐시는 **TTL**, 복구 데이터는 **AOF**

### 쉽게 이해하기 (학습용)
- Redis 데이터가 재생성 가능한 캐시인지 중요한 세션인지 먼저 정해야 TTL·제거·영속성·복구 정책을 맞게 결정할 수 있음
