## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 레지스트리(Model Registry)**: 머신러닝 모델 아티팩트의 불변 버전(Immutable Version), 학습 코드 커밋, 훈련 데이터셋 해시, 하이퍼파라미터의 계보(Lineage), 오프라인 검증 성적표, 배포 승인 상태(Staging / Production) 및 롤백 별칭(Alias)을 중앙 집중 관리하는 MLOps 거버넌스 저장소.
- **모델 출처 유실 및 무단 배포 위험(Untracked Artifacts & Shadow Deployment)**: 모델 파일이 공유 폴더나 로컬 디스크에 방치되어 어떤 데이터로 학습되었는지 재현이 불가능하고 검증되지 않은 모델이 프로덕션에 무단 배포되는 위험.

</details>

- 정의/개념: 학습된 머신러닝 모델 아티팩트의 **버전, 메타데이터, 계보(Lineage) 및 승인 배포 상태를 중앙 통제하는 MLOps 저장소**
- 배경/필요성: 모델 파일의 수동 공유 및 버전 미관리로 인한 **학습 데이터 출처 유실, 미검증 모델의 무단 배포 및 감사 추적 불가 위험** 직면

#### 한줄 요약

- 불변 아티팩트와 계보(Lineage) 추적 및 4-Eyes Approval 거버넌스를 통해 모델의 안전한 승격과 무중단 롤백을 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **모델 계보(Model Lineage)**: 모델 아티팩트가 생성된 원천 데이터(DVC 해시), 피처 버전(Feast), 학습 코드(Git Commit), 훈련 파이프라인 ID 간의 암호학적 연결 관계.
- **프로덕션 별칭(Production Alias)**: 추론 서빙 엔드포인트가 모델 버전 번호(v1, v2)가 아닌 `champion` 같은 논리적 별칭을 바라보게 하여 무중단 배포 및 즉각 롤백을 구현하는 기법.

</details>

- 한 번 등록된 아티팩트는 변조 및 덮어쓰기가 불가능한 **불변 버전 관리(Immutable Versioning)**
- 성능 지표, 보안 스캔, 규제 적합성을 통과해야 승격되는 **승인 게이트(Approval Gate)**
- 모델 등록, 승인, 배포, 폐기의 전 행위를 암호학적으로 기록하는 **감사 추적성(Audit Trail)**

#### 한줄 요약

- 불변 버전, 2인 승인 정책, 계보 추적, 별칭 기반 무중단 배포를 통해 AI 거버넌스를 완성

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 레지스트리 5대 핵심 아키텍처 계층**: Artifact Store(바이너리 보관), Lineage Graph(계보 추적), Validation Evidence(검증 성적표), Approval Policy(승인 거버넌스), Audit Log(감사 이력).

</details>

```text
[ 모델 레지스트리(MLflow Model Registry) 아키텍처 및 거버넌스 구조도 ]

 1. [ 모델 아티팩트 저장소 (Artifact Store: S3 / GCS) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • model.onnx / model.pkl + SHA-256 Hash + 입출력 Signature │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 2. [ 계보 추적 그래프 (Lineage Graph Engine) ] ─────────────────┐
    • Git Commit + DVC Dataset Hash + Feast Feature Version      │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 3. [ 검증 증적 및 승인 정책 (Validation & RBAC Approval) ] ─────┐
    • 오프라인 평가 지표 (AUC 0.94) + 보안 취약점 검증 완료      │
    • 4-Eyes Approval (데이터 사이언티스트 등록 ➔ ML 엔지니어 승인)│
    └────────────────────────────┬────────────────────────────────┘
                                 │ (Production 승격)
                                 ▼
 4. [ 프로덕션 별칭 제어 (Production Alias: Champion / Challenger) ]
    • Serving Endpoint ➔ `champion` Alias ➔ Model v2.3 포인터 변경
```

선의 의미: 아티팩트와 계보가 등록되면 검증 증적에 따라 2인 승인을 거쳐 Production Alias가 신규 버전으로 전환되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 아티팩트 저장소 (Artifact) | 모델 바이너리 파일과 **SHA-256 무결성 해시, 입출력 모델 서명(Signature) 불변 보관** |
| 계보 그래프 (Lineage) | 코드 커밋, **훈련 데이터 스냅샷, 피처 버전, 하이퍼파라미터 간의 1:1 관계 추적** |
| 검증 증적 (Validation) | 오프라인 벤치마크 점수, **편향성(Fairness), 보안 검사 결과를 모델 버전과 결합 보관** |
| 승인 정책 (Approval RBAC) | 역할 기반 접근 제어로 **2인 승인(4-Eyes)을 거쳐 Staging에서 Production으로 승격** |
| 별칭 제어기 (Alias) | `champion` 별칭 포인터를 변경하여 **추론 API의 무중단 배포 및 즉각 롤백 수행** |

#### 한줄 요약

- 아티팩트, 계보, 검증 증적, 승인 정책, 별칭 제어기가 결합하여 모델 레지스트리를 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **모델 레지스트리 5단계 수명주기**: 모델 아티팩트 등록 $\to$ 계보 결속 및 검증 $\to$ 2인 승인(4-Eyes) $\to$ Production Alias 전환 $\to$ 이상 감지 시 즉각 롤백.

</details>

```text
[ Model Registry 모델 승격, 배포 및 무중단 롤백 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 학습 완료 후 Artifact & Signature 등록│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. Git/DVC Lineage 결속 및 오프라인 검증
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. Staging 승격 및 2인 승인(4-Eyes) 심사│
 ├───────────────────┬────────────────────┤
 │ 승인 거부 (결격)  │ 승인 완료 (적합)   │
 │ • 재실험 요구     │ • Production 승격  │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. Champion Alias 포인터 갱신 무중단 배포│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 운영 이상 시 Champion Alias 이전 롤백│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 등록: Kubeflow 파이프라인이 학습을 마치고 `model.onnx`와 SHA-256 해시를 MLflow에 `v3.0`으로 등록.
2. 계보 결속: Git 커밋 해시와 S3 데이터셋 스냅샷 해시를 연결하고 AUC 0.95 검증 리포트를 첨부.
3. 2인 승인: ML 엔지니어와 리드 아키텍트가 검증 증적을 검토하고 전자서명으로 Production 승격을 승인.
4. 별칭 전환: KServe 추론 서버가 바라보는 `champion` 별칭의 포인터를 `v2.0`에서 `v3.0`으로 0.1초 만에 전환.
5. 즉각 롤백: 운영 중 응답 지연이 발생하자 `champion` 별칭을 즉시 `v2.0`으로 되돌려 1초 내에 장애를 복구.

#### 한줄 요약

- 아티팩트 등록 $\to$ 계보 결속 $\to$ 2인 승인 $\to$ 별칭 전환 $\to$ 즉각 롤백의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Model Registry vs Experiment Tracker vs Artifact Store**: 승인 및 배포 통제(Registry), 실험 파라미터 비교(Tracker), 단순 바이너리 저장소(Artifact Store).

</details>

| 구분 | 모델 레지스트리 (Model Registry) | 실험 추적기 (Experiment Tracker) | 아티팩트 저장소 (Artifact Store) |
|:---|:---|:---|:---|
| **적용 기준** | 상용 환경 배포 승인, 거버넌스 감사, 롤백 제어 | 모델 개발 단계의 수많은 하이퍼파라미터 튜닝 비교 | 대용량 모델 가중치 파일의 물리적 안전 저장 |
| **핵심 특징** | **승인 상태(Staging/Prod), Production Alias, Lineage 관리** | **Run별 파라미터, 손실 함수 그래프, 메트릭 시각화 비교** | **S3/GCS 객체 스토리지, SHA-256 무결성 바이너리 보관** |
| **한계** | 승격된 최종 후보 모델 관리 위주로 실험 중간 과정 미포함 | 배포 승인 워크플로우 및 프로덕션 별칭 제어 기능 부재 | 메타데이터, 계보, 승인 워크플로우 관리 불가 |

#### 한줄 요약

- 실험 비교는 Experiment Tracker, 물리 저장은 Artifact Store, 운영 배포 승인과 거버넌스는 Model Registry를 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **2인 승인(4-Eyes Principle)**: 금융 및 미션 크리티컬 시스템에서 단일 엔지니어가 독단적으로 모델을 배포하지 못하도록 승인자를 분리하는 규제 준수 통제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 개발자가 검증되지 않은 모델을 운영에 임의 배포 | **`RBAC` 역할 분리 및 `4-Eyes Approval (2인 승인)` 워크플로우 강제** | 무단 배포 사고 원천 차단 |
| 데이터셋 출처가 누락되어 운영 모델의 결함 원인 규명 불가 | **`Artifact Hash + Git Commit + DVC 해시` 계보(Lineage) 필수 결속** | 모델 100% 추적성 및 재현성 확보 |
| 모델 레지스트리 장애 시 전체 서빙 엔드포인트 연쇄 마비 | **Alias 라우팅 메타데이터 로컬 캐싱 및 레지스트리 다중화 구성** | 레지스트리 장애 격리 및 가용성 확보 |

#### 한줄 요약

- 2인 승인 강제, 3중 계보 결속, 별칭 캐싱을 통해 모델 레지스트리의 신뢰성과 안정성을 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **AI 규제 준수 및 EU AI Act 거버넌스(AI Compliance)**: 고위험 AI 모델에 대한 데이터 출처, 위험 평가, 감사 로그 보관을 의무화하는 글로벌 인공지능 법률 규제.

</details>

- **모델 레지스트리**는 AI 모델의 배포 승인과 규제 감사를 총괄하는 MLOps 거버넌스의 핵심 중심점이며, 불변 아티팩트와 계보 관리 및 별칭 기반 무중단 롤백을 통해 신뢰할 수 있는 엔터프라이즈 AI를 완성해야 함

#### 한줄 요약

- 불변 버전과 계보 추적 및 2인 승인 거버넌스를 통해 안전하고 검증된 AI 모델 배포를 완성
