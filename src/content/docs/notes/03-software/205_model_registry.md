## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **모델 레지스트리(Model Registry)**: 불변 모델 버전에 코드•데이터•학습 계보와 평가•승인 상태를 연결해 배포를 통제하는 저장소이다.
- **모델 계보(Model Lineage)**: 모델을 만든 코드•데이터•피처•학습 실행과 평가 결과의 관계를 추적하는 기록이다.

</details>

- 정의/개념: **모델 버전•계보•승인 상태를 연결해 배포 통제**하는 저장소
- 배경/필요성: 파일 저장만으로 **운영 승인•배포•복귀 통제 곤란**

#### 한줄 요약
- 모델마다 출생 기록과 시험 성적표를 붙이고 승인된 번호만 운영 이름표가 가리키게 한다

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **승인 게이트•운영 별칭**: 승인 게이트는 승격 조건을 검사하고 운영 별칭은 현재 배포할 불변 모델 버전을 가리킨다.
- **불변 버전(Immutable Version)**: 등록 후 내용을 덮어쓰지 않고 변경마다 새 번호를 부여하는 모델 버전이다.
- **산출물 해시(Artifact Hash)**: 모델 파일 내용으로 계산해 변조 여부와 배포 대상의 동일성을 확인하는 요약값이다.

</details>

- **불변 버전•산출물 해시 기반** 배포 결과 재현
- **코드•데이터•학습•평가 계보** 추적
- **승인 게이트•운영 별칭 기반** 승격•복귀 통제

#### 한줄 요약
- 모델 파일을 고치지 않고 새 번호로 쌓아 두면 운영 이름표만 이전 번호로 돌려 같은 모델을 다시 배포할 수 있다

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **승인 정책**: 승인 정책은 검증 증적과 권한 조건을 바탕으로 모델의 단계 상태와 운영 별칭 전환을 통제한다.
- **모델 산출물(Model Artifact)**: 학습 결과로 생성된 모델 파일•가중치•실행 명세 등 배포 가능한 결과물이다.
- **검증 증적(Validation Evidence)**: 성능•무결성•출처가 승인 기준을 충족했음을 입증하는 평가 결과와 기록이다.
- **모델 서명(Model Signature)**: 모델이 받는 입력과 내보내는 출력의 이름•자료형•형상을 명시한 계약이다.
- **감사 로그(Audit Log)**: 등록•승인•별칭 변경•배포•복귀 행위의 주체와 시각을 변경하기 어렵게 기록한 이력이다.

</details>

```text
모델 레지스트리 구조
      |
      +-- 산출물•출처
      |         +-- [모델 산출물]
      |         +-- [계보 메타]
      |
      +-- 승인•통제
                +-- [검증 증적]
                +-- [승인 정책]
                +-- [감사 로그]
```

| 구성요소 | 책임 |
|:---|:---|
| 모델 산출물 | 불변 파일•**해시•모델 서명** 보관 |
| 계보 메타 | **코드•데이터•학습 관계** 추적 |
| 검증 증적 | **성능•무결성•출처** 합격 근거 |
| 승인 정책 | 단계 상태와 **운영 별칭 전환** 제어 |
| 감사 로그 | **등록•승인•배포•복귀** 이력 저장 |


#### 한줄 요약
- 모델 파일과 학습 출처•시험 결과를 묶고 승인 정책이 운영 이름표를 바꾼 기록까지 남긴다

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 후보 버전 등록**: 모델 산출물•해시•계보를 새 불변 버전으로 등록하는 단계이다.
- **2. 평가•계보 검증**: 성능•무결성•데이터 출처와 재현 가능성을 승인 기준에 대조하는 단계이다.
- **3. 승인 상태 전환**: 승인 주체와 근거를 기록하고 후보의 단계 상태를 변경하는 단계이다.
- **4. 운영 별칭•승인 버전 배포**: 별칭이 가리키는 불변 버전을 운영에 반영하는 단계이다.
- **5. 운영 버전 기록**: 환경별 실제 배포 버전과 복귀 이력을 레지스트리에 연결하는 단계이다.

</details>

```text
1. 후보 버전 등록
      |
      v
2. 평가•계보 검증
      |
      +-- 기준 미달 --> 승격 거부•증적 보완
      |
      +-- 기준 충족
              |
              v
3. 승인 상태 전환
      |
      v
4. 운영 별칭•승인 버전 배포
      |
      +-- 배포 검증 실패 --> 이전 별칭•모델 복귀
      |
      +-- 배포 검증 통과
              |
              v
5. 운영 버전 기록
```

**동작 원리**

1. **후보 버전 등록**: **산출물 해시•계보 불변 등록**
2. **평가•계보 검증**: **성능•무결성•출처** 합격 판정
3. **승인 상태 전환**: 승인자•근거와 **단계 상태 변경**
4. **운영 별칭•승인 버전 배포**: 검증 버전 운영 반영
5. **운영 버전 기록**: 환경별 **배포•복귀 이력** 저장


#### 한줄 요약
- 후보 모델의 파일•출처•성적을 확인해 승인하고 운영 이름표를 해당 번호로 바꾼다

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **모델 레지스트리 역할**: 실험•파일 증거를 운영 승인과 연결해 승격•배포•복귀 통제
- **머신러닝 운영(Machine Learning Operations, MLOps)**: 모델 생명주기를 자동화•통제하는 운영 체계이다.
- **실험 추적기(Experiment Tracker)**: 학습 실행별 파라미터•코드•데이터 버전•지표를 기록해 후보 실험을 비교하고 재현하도록 돕는 도구이다.
- **산출물 저장소(Artifact Store)**: 모델 등 대용량 파일을 불변 객체로 보관하고 해시로 무결성을 확인하는 저장소이다.

</details>

| MLOps 저장소 | 모델 레지스트리 | 실험 추적기 | 산출물 저장소 |
|:---|:---|:---|:---|
| 적용 기준 | 운영 **승격•배포•복귀 통제** | 후보 실험 **재현•비교** | 대용량 파일 **보관•무결성** |
| 핵심 특징 | **승인 상태•운영 별칭** 관리 | **학습 실행•지표** 기록 | **불변 모델 파일** 보관 |
| 한계 | 잘못된 승인•**별칭 오변경** | 운영 버전 **통제 부족** | 계보•승인 **정보 부족** |

> 요약: 레지스트리는 실험•파일 증거를 운영 승인에 연결

#### 한줄 요약
- 파일 창고와 실험 기록은 재료를 보관하고 레지스트리는 그 증거로 운영할 모델 번호를 승인한다

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **단일 장애**: 레지스트리의 단일 장애는 승인 모델 조회와 별칭 전환을 막아 전체 모델 배포 통제를 중단시킬 수 있다.
- **역할 기반 접근 제어(Role-Based Access Control, RBAC)**: 사용자의 역할에 따라 모델 등록•승인•별칭 변경 권한을 분리하는 방식이다.
- **데이터 스냅숏(Data Snapshot)**: 특정 시점의 학습 데이터를 변경 불가능한 버전으로 고정한 사본이다.
- **2인 승인(Four-Eyes Approval)**: 한 사람의 실수나 권한 오용을 막기 위해 별도 승인자의 확인을 요구하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 승인 없는 **운영 별칭 변경** | RBAC•2인 승인•**감사 로그** | 오배포•오복귀 **방지** |
| 산출물•계보의 **불일치** | 해시•데이터 스냅숏 **결속** | 모델 결과 **재현성** |
| 레지스트리의 **단일 장애** | 복제•백업•**복구 시험** | 배포 통제 **지속성** |
| 폐기 모델의 **장기 잔존** | 보존•폐기•**규제 정책 적용** | 비용•위험 **축소** |

#### 한줄 요약
- 신용 모델은 누가 어떤 데이터로 만든 버전을 승인했는지 함께 확인한다



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **운영 별칭**: 평가 증적과 계보가 합격 조건을 충족한 불변 버전만 운영 별칭으로 승격해야 한다.
- **모델 승격(Model Promotion)**: 검증된 후보 버전의 승인 단계를 높이고 운영 별칭이 가리키도록 변경하는 절차이다.
- **모델 복귀(Model Rollback)**: 장애나 품질 저하 시 운영 별칭을 이전에 검증된 불변 버전으로 되돌리는 절차이다.

</details>

- **평가 증적•계보** 충족 버전만 **운영 별칭 대상으로 승격**

#### 한줄 요약
- 파일•학습 출처•시험 결과를 함께 승인하고 운영 이름표를 이전 번호로 돌릴 수 있어야 한다
