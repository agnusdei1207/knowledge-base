## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **전가상화(Full Virtualization)**: 게스트 수정 없이 가상 하드웨어를 제공하는 방식
- **반가상화(Paravirtualization)**: 수정된 게스트가 하이퍼콜로 중재를 요청하는 방식
- **컨테이너(Container)**: 호스트 커널을 공유하는 프로세스 격리 단위

</details>

- 정의/개념: **전가상화•반가상화•컨테이너** 는 게스트 수정 여부와 호스트 커널 공유 범위가 서로 다른 **격리 실행 방식**
- 배경/필요성: 워크로드마다 게스트 호환성•격리 강도•배치 밀도 요구가 달라 **실행 경계 선택이 필요**

#### 한줄 요약

- 게스트 수정과 커널 공유 범위에 따른 **격리 방식**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **하이퍼콜(Hypercall)**: 수정된 게스트가 하이퍼바이저 기능과 자원 중재를 요청하는 호출
- **호스트 커널 공유**: 여러 컨테이너가 같은 운영체제 커널을 사용해 기동시간과 자원 사용을 줄이는 구조

</details>

- 전가상화는 **미수정 게스트•독립 커널** 지원
- 반가상화는 **하이퍼콜** 로 장치 중재 비용 절감
- 컨테이너는 **호스트 커널 공유** 로 시작시간•자원 절감

#### 한줄 요약

- 미수정 게스트•하이퍼콜•**커널 공유**의 경계 차이

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **하이퍼바이저(Hypervisor)**: 가상머신의 물리 자원 접근을 중재하는 계층
- **워크로드(Workload)**: 가상머신이나 컨테이너 안에서 실행하는 응용과 처리 작업의 집합

</details>

```text
전가상화
[워크로드] -- [미수정 게스트] -- [자원 중재 경계: 하이퍼바이저]

반가상화
[워크로드] -- [수정 게스트] -- [자원 중재 경계: 하이퍼바이저]

컨테이너
[워크로드] -- [컨테이너 프로세스] -- [자원 중재 경계: 호스트 커널]
```

선의 의미: 위 가지는 워크로드가 선택할 수 있는 세 대안 실행 계층이고, 아래 가지는 각 계층이 공통 자원 중재 경계에 결합되는 정적 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 | **자원 접근 요청** |
| 미수정 게스트 | 전가상화의 **독립 커널 실행** |
| 수정 게스트 | 반가상화의 **하이퍼콜 실행** |
| 컨테이너 프로세스 | 호스트 **커널 공유 격리** |
| 자원 중재 경계 | **권한•자원 접근 통제** |

#### 한줄 요약

- 미수정•수정 게스트와 컨테이너의 **중재 경계 구조**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **커널 공유 허용 판정**: 호스트 커널의 응용 프로그램 이진 인터페이스(Application Binary Interface, ABI)와 공격면을 공유해도 되는지 확인하는 단계
- **게스트 수정 가능성 판정**: 게스트 커널을 하이퍼콜 방식으로 변경할 수 있는지 확인하는 단계

</details>

```text
┌──────────────────────────────┐
│ 워크로드 격리 방식 결정     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 커널 공유 허용 판정      │
└───────┬──────────────────────┘
        ├─ 허용 ────────────────▶ [컨테이너]
        │ 불가
        ▼
┌──────────────────────────────┐
│ 2. 게스트 수정 가능성 판정  │
└───────┬──────────────────────┘
        ├─ 수정 가능 ───────────▶ [반가상화]
        └─ 수정 불가 ───────────▶ [전가상화]
```

**동작 원리**

- **1. 커널 공유 허용 판정**: ABI 호환성과 격리 요구 확인
- **2. 게스트 수정 가능성 판정**: 하이퍼콜 적용 가능 여부 확인

#### 한줄 요약

- 커널 공유와 게스트 수정 가능성으로 **격리 방식 선택**

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>


</details>

| 격리 실행 방식 | 전가상화 | 반가상화 | 컨테이너 |
|:---|:---|:---|:---|
| 적용 기준 | 게스트 수정 불가•**커널 격리** | 게스트 수정 가능•**중재 성능 우선** | 커널 호환•**빠른 배포 우선** |
| 핵심 특징 | 미수정 게스트•**독립 커널** | 하이퍼콜•**수정 게스트** | 호스트 **커널 공유** |
| 한계 | 중재 비용•**낮은 밀도** | 게스트 수정•**호환 제약** | 커널 공유 **공격면** |

> 요약: **게스트 수정 여부•커널 공유 범위** 로 **격리 방식** 구분

#### 한줄 요약

- 미수정은 **전가상화**, 수정 가능은 반가상화, 공유는 컨테이너

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최소 권한(Least Privilege)**: 작업에 필요한 최소 자원과 권한만 부여하는 보안 원칙
- **제어 그룹(Control Group, cgroup)**: 프로세스 집합의 CPU•메모리 사용을 제한하고 계측하는 리눅스 기능
- **시끄러운 이웃(Noisy Neighbor)**: 같은 장비의 다른 워크로드가 자원을 과도하게 써 성능을 떨어뜨리는 현상
- **이미지 출처 증명(Image Provenance)**: 실행 이미지를 누가 어떤 재료와 절차로 만들었는지 검증할 수 있는 기록
- **반가상 장치 드라이버**: 게스트가 하이퍼바이저와 협력해 장치 모사 비용을 줄이는 드라이버
- **자원 제한(Resource Limit)**: 워크로드가 넘을 수 없는 사용량 상한
- **자원 예약(Resource Reservation)**: 워크로드가 항상 보장받을 최소 자원량
- **취약점 검사(Vulnerability Scanning)**: 이미지의 패키지•설정을 알려진 보안 결함 목록과 비교하는 점검
- **공급망 신뢰성(Supply-chain Trust)**: 이미지의 출처•서명•구성 재료가 검증되어 빌드부터 배포까지 변조되지 않았음을 신뢰할 수 있는 성질

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 커널 취약점이 여러 컨테이너에 **피해 전파** | 커널 패치•**최소 권한** 과 고위험 작업 VM 격리 | **공격면•피해 범위** 축소 |
| 자원 상한이 없어 **시끄러운 이웃 발생** | **cgroup 제한•예약** 과 워크로드별 사용량 계측 | **성능 간섭** 통제 |
| 출처 불명 이미지로 **악성 코드•취약 구성 유입** | 서명된 이미지•**출처 증명•취약점 검사** | **공급망 신뢰성** 확보 |
| 전가상화의 장치 모사로 **기동•처리 비용 증가** | **반가상 장치 드라이버** 와 실제 처리량 계측 | 격리를 유지하며 **오버헤드 절감** |

#### 한줄 요약

- 커널 공격면•자원 간섭•**이미지 신뢰성** 통제

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **게스트 수정 여부**: 미수정 게스트는 전가상화를 고르는 기준
- **게스트 수정 가능성**: 수정 커널을 쓸 수 있으면 반가상화를 고르는 기준
- **커널 공유**: 경량 실행이 중요하면 컨테이너를 고르는 기준

</details>

- **게스트 수정 불가•커널 격리** 는 전가상화, 수정 가능은 반가상화, **커널 공유** 는 컨테이너 선택

#### 한줄 요약

- 커널 공유와 게스트 수정 여부에 맞는 **격리 방식 선택**
