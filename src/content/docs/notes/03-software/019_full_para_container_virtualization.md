## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상화 3대 패러다임**: 하드웨어를 완전 에뮬레이션하는 전가상화, 게스트 커널을 수정하여 통신하는 반가상화, 호스트 커널을 공유하는 컨테이너 가상화.
- **하이퍼콜(Hypercall)**: 반가상화 환경에서 게스트 OS가 하이퍼바이저에 직접 특권 동작을 요청하는 인터페이스(시스템 콜과 유사).

</details>

- 정의/개념: 하드웨어 에뮬레이션(전가상화), 커널 수정 하이퍼콜(반가상화), **호스트 커널 공유(Namespaces/cgroups 컨테이너)** 로 구분되는 가상화 계층 체계
- 배경/필요성: VM은 인스턴스마다 게스트 OS 전체를 사본으로 올려 커널·부팅 비용을 중복해서 치르므로, 호스트 커널은 공유하고 네임스페이스·cgroups로 격리만 얹은 컨테이너 계층을 두어 그 중복을 걷어내고 배포 밀도와 기동 시간을 자릿수 단위로 바꿀 필요

#### 한줄 요약
- 격리 수준과 오버헤드 요구사항에 따라 전가상화, 반가상화, 컨테이너 가상화를 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Namespaces & cgroups**: 리눅스 커널의 프로세스 격리(PID, Mount, Network)와 하드웨어 자원(CPU, Memory, I/O) 할당 한도를 통제하는 컨테이너의 근간.
- **Binary Translation**: 하드웨어 가상화 지원이 없을 때 게스트 OS의 특권 명령을 런타임에 안전한 명령어로 동적 치환하는 소프트웨어 전가상화 기법.

</details>

- **전가상화(Full Virtualization)**: 게스트 OS 수정 없이 하드웨어 가상화(Intel VT-x)를 통해 완전한 독립 이종 OS 구동
- **반가상화(Para-virtualization)**: 게스트 OS 커널을 수정하여 **하이퍼콜(Hypercall)** 직결로 에뮬레이션 오버헤드 최소화
- **컨테이너(Container)**: 게스트 OS 없이 **Namespaces 및 cgroups**를 통해 프로세스 수준 초경량 격리 달성

#### 한줄 요약
- 전가상화는 호환성, 반가상화는 I/O 성능, 컨테이너는 경량성과 초고속 배포에 특화된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **virtio**: 전가상화 환경에서도 디스크/네트워크 I/O 계층에만 반가상화 드라이버를 적용하여 네이티브 수준 속도를 내는 표준 인터페이스.

</details>

```text
[가상화 3대 모델 아키텍처 비교]
|-- 전가상화 (Full Virtualization)
|   |-- 하드웨어 (VT-x)
|   |-- 하이퍼바이저 (KVM/ESXi)
|   `-- 미수정 게스트 OS와 애플리케이션
|-- 반가상화 (Para-virtualization)
|   |-- 하드웨어와 하이퍼바이저 (Xen)
|   `-- 하이퍼콜 수정 커널과 애플리케이션
`-- 컨테이너 가상화 (Container)
    |-- 하드웨어와 호스트 OS 커널
    `-- 컨테이너 엔진과 격리 애플리케이션
```

선의 의미: 계층 및 가상화 추상화 수준

| 구성요소 | 책임 |
|:---|:---|
| 전가상화 | EPT 기반 **미수정 표준 OS** 실행 |
| 반가상화 | 수정 커널의 **하이퍼콜** 직접 호출 |
| 컨테이너 | **호스트 커널 공유** 기반 프로세스 격리 |

#### 한줄 요약
- 전가상화·반가상화·컨테이너는 게스트 OS를 어디까지 복제하느냐로 갈리며, 복제 범위가 줄수록 격리 경계도 함께 얕아진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마이크로VM(MicroVM)**: Firecracker, Kata Containers처럼 컨테이너마다 초경량 KVM VM을 1:1로 씌워 컨테이너의 속도와 VM의 보안 격리를 결합한 기술.

</details>

```text
서비스 배포 및 가상화 기술 선정
        │
   호스트와 다른 이종 OS(Windows/FreeBSD) 구동 또는 완전한 하드웨어 격리가 필수인가?
   ┌────┴─────┐
  예           아니오 (동일 Linux 환경 및 초경량 고밀도 우선)
   │             │
VM 가상화 채택   컨테이너 가상화 채택 (Docker / Kubernetes)
   │             │
게스트 커널 수정이 가능한가?  멀티테넌트 환경에서 커널 레벨 보안 격리가 필요한가?
┌──┴───┐                    ┌────┴─────┐
예      아니오               예           아니오
│       │                   │             │
반가상화 전가상화 (VT-x)     마이크로VM    순수 리눅스 컨테이너
(Xen)   (KVM/ESXi)          (Kata/Firecracker) (Docker)
```

#### 한줄 요약
- 이종 OS와 강한 격리를 요구하면 게스트 OS 복제 비용을 감수하고 동일 커널에서 밀도를 요구하면 격리 깊이를 내주므로, 두 갈래는 같은 축의 양 끝이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Kata Containers**: OCI 호환 컨테이너 런타임으로, 각 Pod/컨테이너를 초경량 QEMU/Cloud-Hypervisor VM 안에서 격리 실행하는 보안 런타임.

</details>

| 비교 항목 | 전가상화 (Full) | 반가상화 (Para) | 컨테이너 (Container) | 마이크로VM (MicroVM) |
|:---|:---|:---|:---|:---|
| 게스트 OS 커널 | 독립 미수정 커널 | **독립 수정 커널** | **없음 (호스트 커널 공유)** | 초경량 독립 커널 (5MB) |
| 성능 오버헤드 | 낮음 (하드웨어 가속) | 매우 낮음 | **거의 전무 (0~1%)** | 극소 (1~2%) |
| 시작/부팅 시간 | 수십 초 ~ 수 분 | 수십 초 | **수 밀리초 ~ 수 초** | 100ms 이내 |
| 메모리 소비 | VM당 수백 MB ~ 수 GB | VM당 수백 MB | **수 MB ~ 수십 MB** | 10~20MB |
| 보안 격리 수준 | **매우 높음 (HW 격리)** | 매우 높음 | 중간 (커널 공유 취약점) | **매우 높음 (HW 격리)** |

#### 한줄 요약
- 순수 속도와 밀도는 컨테이너, 보안과 이종 OS는 전가상화, 두 마리 토끼는 마이크로VM이 잡는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Rootless Container**: root 권한 없이 일반 유저 계정(User Namespace)으로 컨테이너 엔진을 구동하여 호스트 탈옥 공격을 무력화하는 보안 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 컨테이너 탈옥(Container Escape)으로 호스트 커널 장악 | **Rootless Container 및 seccomp / AppArmor** 프로파일 강제 | 유해 시스템 콜 차단 및 호스트 침해 원천 차단 |
| 전가상화 환경에서 디스크/네트워크 I/O 병목 | **virtio 반가상화 디바이스 드라이버** 설치 | I/O 에뮬레이션 제거 및 처리 속도 3배 향상 |
| 멀티테넌트 SaaS 환경에서 컨테이너 간 자원 간섭 | **마이크로VM(Kata Containers / Firecracker)** 도입 | 하드웨어 레벨 테넌트 완전 격리 및 100ms 콜드스타트 |
| 컨테이너 메모리 폭증으로 인한 노드 다운 | cgroups v2 `memory.max` 및 OOM 점수 조정 | 특정 컨테이너 단독 OOM-Kill로 시스템 가용성 보호 |

#### 한줄 요약
- 컨테이너의 밀도와 기동 속도는 커널을 공유해 얻은 것이라 격리 강도를 대가로 내주므로, 신뢰 경계가 다른 워크로드는 마이크로VM으로 되돌려 밀도 대신 격리를 사들인다.

## Ⅶ. 결론

- 일반 MSA는 **컨테이너**, 보안 격리는 **마이크로VM** 선택

#### 한줄 요약
- 가상화 기술은 격리성과 성능의 트레이드오프 관계에 있으며, 서비스 특성에 따른 맞춤형 계층 배치가 필수적이다.
