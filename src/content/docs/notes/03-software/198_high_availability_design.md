## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **목표 가용성**: 고가용성 설계는 독립 장애 도메인과 자동 전환을 통해 계획·비계획 장애에도 목표 가용성을 유지한다.

</details>

- 정의/개념: 독립 장애 도메인과 자동 전환으로 **목표 가용성**을 유지하는 시스템 구조
- 배경/필요성: 단일 자원 구조로는 장애 시 **서비스 전체 중단** 방지 불가

### 쉽게 이해하기 (학습용)
- 한 발전기가 멈추면 독립 전원의 예비 발전기로 부하를 넘기듯, 장애 도메인을 나누고 준비된 인스턴스로 요청을 전환한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **헬스 체크·펜싱**: 헬스 체크는 실제 요청 처리 가능성을 판정하고 펜싱은 이전 활성 노드의 쓰기 권한을 차단해 안전하게 전환한다.

</details>

- **장애 도메인 분리·다중화** 기반 지속 처리
- **Active-Active·Active-Standby** 기반 이중화
- **헬스 체크·펜싱** 기반 안전 전환
- **상태 복제·N-1 용량** 기반 목표 가용성
- **SLO·오류 예산** 기반 가용성 목표 관리
- **준비 상태·부하 차단** 기반 핵심 요청 보호

### 쉽게 이해하기 (학습용)
- 두 매장을 다른 전원과 망에 두고 한쪽이 멈추면 상태 확인과 펜싱 뒤 다른 쪽으로 손님을 보내 동시 장애와 이중 쓰기를 피한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **쿼럼·펜싱**: 쿼럼·펜싱은 하나의 대체 인스턴스만 승격하고 이전 노드의 쓰기를 차단해 단일 쓰기를 보장한다.

</details>

```mermaid
block
    columns 1
    A["트래픽 제어"]
    B["활성 인스턴스"]
    C["대체 인스턴스"]
    D["쿼럼·펜싱"]
    E["상태 저장소"]
    A --- B
    A --- C
    B --- D
    C --- D
    D --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 트래픽 제어 | 정상·**전환 경로 관리** |
| 활성 인스턴스 | 정상 요청·**업무 처리** |
| 대체 인스턴스 | 독립 도메인·**부하 인계** |
| 쿼럼·펜싱 | 단일 쓰기·**승격 통제** |
| 상태 저장소 | 업무 상태·**복제 정합성** |

> 요약: 장애 도메인 다중화와 **쿼럼·상태 복제**로 안전 전환

### 쉽게 이해하기 (학습용)
- 트래픽 제어가 활성·대체 인스턴스를 잇고 쿼럼이 단일 쓰기를 보장하며 상태 저장소가 업무 상태를 대체 노드에 전달한다.
## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **2. 펜싱·승격 요청**: 트래픽 제어는 장애 판정 뒤 이전 노드의 쓰기 권한 차단과 대체 인스턴스 승격을 요청한다.

</details>

```mermaid
sequenceDiagram
    participant A as 활성 인스턴스
    participant C as 트래픽 제어
    participant Q as 쿼럼·펜싱
    participant N as 대체 인스턴스
    participant S as 상태 저장소
    A-->>C: 1. 상태 판정 결과
    C->>Q: 2. 펜싱·승격 요청
    Q-->>C: 3. 승격 승인
    C->>N: 4. 트래픽 경로
    N->>S: 5. 상태 정합성 조회
    S-->>N: 업무 상태
    N-->>C: 복구 검증 결과
```

**동작 원리**

1. **상태 판정 결과**: 의존성·요청 처리 가능성 판정
2. **펜싱·승격 요청**: 이전 노드 쓰기 권한 차단
3. **승격 승인**: 쿼럼으로 단일 대체 선택
4. **트래픽 경로**: 정상 대체로 요청 전달
5. **상태 정합성 조회**: 업무 거래와 복제 상태 확인

> 요약: **펜싱·쿼럼 승인** 후 트래픽 전환·상태 검증

### 쉽게 이해하기 (학습용)
- 활성 노드가 멈추면 쓰기 권한을 먼저 끊고 쿼럼 승인을 받은 대체 노드가 복제 상태를 확인한 뒤 요청을 인계한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **Active-Active**: Active-Active는 둘 이상의 활성 인스턴스가 동시에 요청을 처리하고 장애 시 남은 인스턴스가 부하를 인계한다.

</details>

| 고가용성 구성 | Active-Active | Hot Standby | Warm Standby |
|:---|:---|:---|:---|
| 적용 기준 | 무중단·**부하 분산** | 짧은 전환·**단일 쓰기** | 비용 절감·**긴 전환 허용** |
| 핵심 특징 | 다중 환경 **동시 처리** | 대기 환경 **즉시 승격** | 대기 환경 **기동 후 승격** |
| 한계 | 쓰기 충돌·**동기화 복잡도** | 유휴 비용·**승격 실패** | 기동·**데이터 복구 지연** |

> 요약: **목표 가용성·비용**에 따라 이중화 방식 선택

### 쉽게 이해하기 (학습용)
- 두 매장이 평소 함께 영업하면 액티브-액티브, 한 매장은 즉시 대기하면 핫 스탠바이, 준비 시간이 필요하면 웜 스탠바이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **분할 뇌**: 분할 뇌는 네트워크 단절 뒤 둘 이상의 노드가 자신을 주 노드로 판단해 동시에 쓰는 장애다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 같은 전원·망의 **공통 실패** | 장애 도메인별 **물리 분리** | 동시 장애 **범위 축소** |
| 감지기의 **오탐 전환** | 다중 신호·**지속 시간 판정** | 불필요한 전환 **방지** |
| 네트워크 단절의 **분할 뇌** | 쿼럼·**펜싱 선행** | 이중 쓰기 **차단** |
| 전환 뒤 **용량 부족** | N-1·최대 **부하 시험** | 목표 가용성 **유지** |
| 훈련 없는 **자동 전환** | 정기 **카오스 테스트** | 감지·승격 절차 **검증** |

### 쉽게 이해하기 (학습용)
- 데이터베이스 전환 때 이전 주 노드의 쓰기 권한을 먼저 차단해야 두 계산대가 같은 장부를 동시에 고치지 않는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **Active-Active**: 동시 처리와 N-1 여유가 검증되면 Active-Active를 선택하고 단일 쓰기 안전성이 우선이면 Hot Standby를 사용한다.

</details>

- 동시 처리와 N-1 여유면 **Active-Active**, 단일 쓰기 우선이면 Hot Standby 선택

### 쉽게 이해하기 (학습용)
- 두 노드가 동시에 쓸 위험이 크면 하나만 주 노드로 두고, 동시 처리와 남은 용량이 검증되면 둘 다 활성화한다.
