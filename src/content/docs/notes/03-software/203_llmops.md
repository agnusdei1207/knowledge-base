## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **LLMOps (Large Language Model Operations)**: 대규모 언어 모델 기반 서비스의 프롬프트 버전 관리, RAG 파이프라인, 가드레일, 비결정성 평가, 비용 관측을 전 주기 통제하는 운영 체계.
- **MLOps vs LLMOps**: 자체 모델 학습 중심(MLOps)과 파운데이션 모델 활용, 프롬프트 엔지니어링, RAG 지식 검색 중심(LLMOps).

</details>

- 정의/개념: 대규모 언어 모델(LLM) 기반 서비스의 **프롬프트, RAG, 가드레일, 모델 배포 및 평가·관측을 자동화하는 운영 체계**
- 배경/필요성: 생성형 AI(Generative AI) 및 대규모 언어 모델(LLM)의 급속한 상용화 과정에서 발생하는 고유한 비결정성(Non-deterministic) 출력, 사실과 다른 환각(Hallucination), 프롬프트 탈옥(Jailbreak) 및 데이터 유출, 천문학적인 API 토큰 호출 비용 통제의 한계를 극복하기 위해, 프롬프트 템플릿과 RAG 벡터 지식을 번들링하여 버전 관리하고, 자동화된 정량 평가(Ragas), 실시간 안전 가드레일(NeMo Guardrails), 시맨틱 캐싱(Semantic Caching) 및 종합 관측성(Observability)을 제공하는 LLMOps 운영 체계를 도입하여 **엔터프라이즈 생성형 AI 서비스의 안전성, 경제성 및 답변 신뢰성을 확보**할 필요

#### 한줄 요약
- 프롬프트, RAG, 가드레일의 형상 관리와 자동 평가를 통해 안전하고 경제적인 생성형 AI 서비스를 구현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Ragas (Retrieval Augmented Generation Assessment)**: Faithfulness(충실도), Answer Relevance(관련성), Context Precision을 정량 측정하는 RAG 평가 프레임워크.
- **Semantic Caching**: 사용자 질문의 임베딩 유사도를 계산하여 동일/유사 질문에 대해 LLM 호출 없이 캐시 응답을 반환하는 비용 절감 기술.

</details>

- 모델 + 프롬프트 + RAG 검색기를 단일 번들로 묶는 **구성 버전 관리(Configuration Bundle)**
- 프롬프트 인젝션과 개인정보(PII)를 실시간 차단하는 **입출력 가드레일(NeMo Guardrails)**
- 저렴한 소형 모델(SLM)과 고성능 모델을 자동 분기하는 **비용 최적화 지능형 라우팅**

#### 한줄 요약
- 구성 번들 관리, 입출력 가드레일, 시맨틱 캐싱 라우팅을 통해 엔터프라이즈 생성형 AI를 안정화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **LLMOps 4대 아키텍처 계층**: Configuration Catalog(프롬프트/RAG 버전), Automated Evaluator(Ragas 평가), LLM Gateway/Guardrails(보안/캐시), Observability(비용/지연 관측).

</details>

```text
[LLMOps 구성]
|-- 구성 카탈로그
|-- 자동 평가기
|-- LLM 게이트웨이
|-- 안전 가드레일
`-- 관측성 플랫폼
```

선의 의미: 계층 및 프롬프트와 RAG 구성을 평가하여 게이트웨이에 배포하고 가드레일과 시맨틱 캐시를 거쳐 호출된 결과를 관측 플랫폼에 기록하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **구성 카탈로그 (Catalog)**| 프롬프트 템플릿, RAG 임베딩 모델, 청크 전략을 **단일 버전 번들로 묶어 이력 관리** | 프롬프트 형상 관리 |
| **자동 평가기 (Evaluator)**| 벤치마크 데이터셋으로 **환각 여부(Faithfulness), 관련성, 유해성을 통계적으로 평가** | Ragas 통계 평가 |
| **LLM 게이트웨이 (Gateway)**| API 토큰 속도 제한, **시맨틱 캐싱(Redis), 질문 난이도별 최적 모델 자동 라우팅** | 비용/트래픽 제어 |
| **안전 가드레일 (Guardrail)**| 악의적 프롬프트 인젝션 차단, **개인정보(PII) 마스킹, 비윤리적 출력 실시간 여과** | NeMo Guardrails |
| **관측성 플랫폼 (Observer)**| 모든 트레이스 스팬에서 **입출력 토큰 비용, 지연시간, 사용자 피드백 메타데이터 수집** | LangSmith 트레이싱 |

#### 한줄 요약
- 카탈로그가 무엇을 배포했는지를, 평가기가 그 구성이 쓸 만한지를, 게이트웨이와 가드레일이 런타임 비용과 위험을 각각 맡으므로 모델 가중치를 건드리지 않고도 품질이 통제된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **LLMOps 서빙 5단계**: 구성 번들 고정 $\to$ Ragas 자동 평가 $\to$ 입력 가드레일 방어 $\to$ 시맨틱 캐시/모델 라우팅 $\to$ 트레이싱 관측.

</details>

```text
생성형 AI 서비스 배포 및 런타임 가동
        │
   1. [구성 번들 고정] 시스템 프롬프트 v2.1과 RAG 벡터 인덱스를 단일 패키지로 번들링
        │
   2. [Ragas 자동 평가] 테스트 데이터셋으로 평가를 수행하여 Faithfulness 점수 0.94 확인
   ┌────┴───────────────────────────┐
  합격 (게이트 통과)               불합격 (환각 감지)
   │                                 │
   • Gateway 등록 및 프로덕션 승인     • 배포 차단 및 프롬프트/청킹 재설계
   │                                 │
   └────┬────────────────────────────┘
        ▼
   3. [입력 가드레일] NeMo Guardrails가 인젝션 패턴을 차단하고 PII 마스킹 수행
        │
   4. [캐시 및 라우팅] Redis 시맨틱 캐시 히트 시 즉시 응답, 미스 시 최적 모델(GPT-4o) 호출
        │
   5. [런타임 관측] LangSmith에 트랜잭션별 토큰 비용($0.005)과 사용자 피드백 기록
```

#### 한줄 요약
- 구성을 버전으로 고정해야 평가 결과가 특정 배포에 귀속되며, 캐싱과 라우팅은 같은 품질을 유지한 채 호출 단가만 낮추는 지점이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Prompt Engineering vs Fine-Tuning vs RAG**: 인프롬프트 제어(Prompt), 가중치 추가 학습(Fine-Tuning), 외부 지식 동적 주입(RAG).

</details>

| 비교 항목 | 프롬프트 엔지니어링 | 파인튜닝 (Fine-Tuning) | 검색 증강 생성 (RAG) |
|:---|:---|:---|:---|
| 핵심 적용 기준 | **응답 톤앤매너, 간단한 JSON 출력 강제** | **특수 도메인 언어/어조, 고정된 형식 내재화** | **최신 사내 규정, 실시간 뉴스, 자주 바뀌는 지식**|
| 모델 가중치 변경 | 변경 없음 (Context 제어) | **도메인 데이터셋으로 가중치 영구 업데이트**| 변경 없음 (외부 벡터 검색 문서 주입) |
| 지식 최신성 갱신 | 매 요청마다 수동 전달 | **지식 갱신 시마다 모델 재학습 필요 (고비용)**| **벡터 DB에 최신 문서 적재 즉시 반영 (실시간)** |
| 환각(Hallucination)| 높음 (모델 자체 지식 의존) | 중간 (특화 영역 개선) | **최저 (검색된 사실적 근거 기반 생성)** |

#### 한줄 요약
- 즉각적 포맷 제어는 프롬프트, 도메인 특화 어조는 파인튜닝, 최신 사실성 보장은 RAG를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Prompt Regression**: 특정 버그 수정을 위해 프롬프트를 수정했다가 기존에 잘 되던 다른 질문들에서 답변 품질이 급락하는 부작용.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프롬프트 수정 시 기존 정상 케이스가 망가지는 회귀(Regression) | **CI 파이프라인에 '골든 평가 데이터셋 회귀 테스트' 자동화 강제** | 프롬프트 품질 회귀 100% 방지 |
| LLM API 호출 비용 폭증으로 인한 운영 예산 초과 | **`Semantic Caching (Redis)` 및 경량 SLM 모델 우선 라우팅** | LLM API 호출 비용 70% 이상 절감 |
| 비결정적 환각(Hallucination) 답변으로 인한 금융 사고 | **RAG Faithfulness 임계치 미달 시 답변 거부(`I don't know`) 가드레일** | 잘못된 거짓 정보 전파 원천 차단 |
| 프롬프트 탈옥(Jailbreak) 및 민감 데이터 유출 공격 | **NeMo Guardrails 및 Llama Guard 기반 실시간 입력 필터링** | 악성 인젝션 및 PII 유출 방어 |

#### 한줄 요약
- 네 대책은 생성 자유도가 만든 회귀·비용·환각 위험을 평가와 캐싱, 거부 응답으로 되사는 선택이며, 가드레일을 조일수록 안전성은 오르고 답변 가능 범위는 좁아진다.

## Ⅶ. 결론

- 파운데이션 모델(Foundation Model)을 활용하여 기업 맞춤형 인텔리전트 서비스를 안정적으로 서빙하는 **가장 핵심적인 생성형 AI 전 주기 엔지니어링 및 런타임 거버넌스 표준**으로 확립되었으며, 실무 구축 시에는 **프롬프트-임베딩-청킹 구성 번들의 형상 관리, Ragas 기반 환각(Faithfulness) 자동 평가 게이트웨이, NeMo Guardrails를 통한 프롬프트 인젝션 및 개인정보(PII) 차단, Redis 시맨틱 캐싱 및 SLM/LLM 지능형 라우팅을 통한 비용 70% 절감, LangSmith 트레이싱 관측**을 결합하여 고품질·저비용의 엔터프라이즈 AI 운영을 완성

#### 한줄 요약
- LLMOps는 프롬프트/RAG 버전 관리, 통계적 평가, 가드레일, 시맨틱 캐싱을 통해 생성형 AI의 환각과 비용을 제어하는 핵심 AI 운영 체계다.
