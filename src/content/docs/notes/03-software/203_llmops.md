## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **LLMOps (Large Language Model Operations)**: 대규모 언어 모델(LLM) 기반 서비스의 개발 및 운영을 위해 프롬프트 템플릿 버전 관리, RAG(검색 증강 생성) 파이프라인 튜닝, 파인튜닝, 입출력 가드레일, 비결정성 평가, 토큰 비용 최적화를 전 주기 관리하는 운영 프레임워크.
- **환각 및 프롬프트 인젝션 위험(Hallucination & Prompt Injection Risk)**: LLM의 비결정적 특성으로 인한 거짓 정보 생성(환각), 악의적 프롬프트 주입을 통한 데이터 유출, 무제한 API 토큰 호출로 인한 비용 폭증 위험.

</details>

- 정의/개념: 대규모 언어 모델(LLM) 기반 서비스의 **프롬프트, RAG, 가드레일, 모델 배포 및 평가·관측을 자동화하는 운영 체계**
- 배경/필요성: 비결정적 텍스트 생성 특성으로 인한 **환각(Hallucination), 프롬프트 인젝션 보안 위협 및 API 호출 비용 폭증 위험** 직면

#### 한줄 요약

- 모델, 프롬프트, RAG, 가드레일의 결합 버전을 체계적으로 평가(Ragas)하고 라우팅하여 안전하고 경제적인 생성형 AI 서비스를 구현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **확률적 통계 평가(Ragas & LLM-as-a-Judge)**: 비결정적 LLM 응답을 충실도(Faithfulness), 답변 관련성(Answer Relevance), 문맥 정밀도(Context Precision) 지표로 정량 점수화하는 기법.
- **LLM 게이트웨이(LLM Gateway)**: API 키 관리, 요청 속도 제한(Rate Limiting), 시맨틱 캐싱(Semantic Cache), 모델 지능형 라우팅을 전담하는 관문.

</details>

- 모델 + 프롬프트 + RAG 검색기를 단일 번들로 묶는 **구성 버전 관리(Configuration Bundle)**
- 프롬프트 인젝션과 개인정보(PII)를 실시간 차단하는 **입출력 가드레일(NeMo Guardrails)**
- 저렴한 소형 모델(SLM)과 고성능 모델을 자동 분기하는 **비용 최적화 모델 라우팅**

#### 한줄 요약

- 프롬프트 회귀 방지, 환각 탐지, 가드레일 보안, 시맨틱 캐싱을 통해 생성형 AI의 운영 복원력을 확보

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **LLMOps 5대 핵심 아키텍처 계층**: Configuration Catalog(프롬프트/RAG 관리), Evaluator(Ragas 평가), LLM Gateway(라우팅/캐시), Guardrail(보안 필터), Observability(LangSmith/Langfuse).

</details>

```text
[ LLMOps 엔드-투-엔드 파이프라인 및 거버넌스 아키텍처 ]

 1. [ 프롬프트 및 구성 관리 (Configuration Catalog) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • Prompt Template v1.2 + RAG Retriever v2.0 + Model (GPT-4o)│
    └────────────────────────────┬────────────────────────────────┘
                                 │ (CI 평가 게이트: Ragas 통계 평가)
                                 ▼
 2. [ 자동 평가 엔진 (Evaluator: LLM-as-a-Judge) ] ───────────────┐
    • Faithfulness(근거성) > 0.90, Toxicity = 0, Token Budget 충족│
    └────────────────────────────┬────────────────────────────────┘
                                 │ (게이트 통과 시 배포)
                                 ▼
 3. [ LLM 게이트웨이 및 가드레일 (LLM Gateway & Guardrails) ] ───┐
    • Input Guard: PII 마스킹 + Prompt Injection 차단            │
    • Semantic Cache (Redis) ➔ 비용 80% 절감                      │
    • Model Router: 난이도별 SLM(Llama-3) / LLM(Claude) 자동 라우팅│
    • Output Guard: 환각(Hallucination) 필터링                   │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 4. [ 통합 관측성 및 피드백 (Observability: LangSmith / Arize) ]
    • Token 사용량, 응답 지연(P99), 사용자 피드백(Thumbs Up/Down)
```

선의 의미: 프롬프트와 RAG 구성을 평가하여 게이트웨이에 배포하고, 가드레일과 시맨틱 캐시를 거쳐 호출된 결과를 관측 플랫폼에 기록하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 구성 카탈로그 (Catalog) | 프롬프트 템플릿, RAG 임베딩 모델, 청크 전략을 **단일 버전 번들로 묶어 이력 관리** |
| 자동 평가기 (Evaluator) | 벤치마크 데이터셋으로 **환각 여부(Faithfulness), 관련성, 유해성을 통계적으로 평가** |
| LLM 게이트웨이 (Gateway) | API 토큰 속도 제한, **시맨틱 캐싱(Redis), 질문 난이도별 최적 모델 자동 라우팅** |
| 안전 가드레일 (Guardrail)| 악의적 프롬프트 인젝션 차단, **개인정보(PII) 마스킹, 비윤리적 출력 실시간 여과** |
| 관측성 플랫폼 (Observer) | 모든 트레이스 스팬에서 **입출력 토큰 비용, 지연시간, 사용자 피드백 메타데이터 수집** |

#### 한줄 요약

- 구성 카탈로그, 평가 엔진, LLM 게이트웨이, 가드레일, 관측 플랫폼이 결합하여 LLMOps를 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **LLMOps 배포 및 운영 5단계 수명주기**: 구성 번들 제출 $\to$ Ragas 자동 평가 $\to$ 가드레일 적용 배포 $\to$ 시맨틱 캐시/라우팅 $\to$ 실시간 환각 관측.

</details>

```text
[ LLMOps 프롬프트/RAG 배포 및 런타임 서빙 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. Prompt + RAG + Model 번들 버전 고정 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. Ragas 기반 환각 및 안전성 자동 평가│
 ├───────────────────┬────────────────────┤
 │ 기준 미달 (환각)  │ 게이트 통과 (합격) │
 │ • 배포 차단/수정  │ • Gateway 등록     │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. Input Guardrail: PII 마스킹 및 방어 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. Semantic Cache 히트 검사 및 모델 호출│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. Langfuse 트레이싱 및 비용/품질 관측 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 구성 고정: 금융 챗봇을 위해 시스템 프롬프트 v2.1과 사내 규정 RAG 벡터 인덱스를 단일 패키지로 번들링.
2. 자동 평가: 500개 테스트 질문 세트로 Ragas 평가를 수행하여 Faithfulness 점수 0.94 달성을 확인하고 승인.
3. 입력 방어: 사용자 질문 진입 시 NeMo Guardrails가 주민등록번호를 자동 마스킹하고 인젝션 패턴을 필터링.
4. 캐시 및 라우팅: Redis Semantic Cache에서 유사 질문 히트 시 10ms 내 응답하고, 미스 시 GPT-4o로 라우팅.
5. 런타임 관측: LangSmith에 트랜잭션별 토큰 비용($0.005)과 사용자 좋아요/싫어요 데이터를 기록하여 다음 개선에 반영.

#### 한줄 요약

- 구성 고정 $\to$ 자동 평가 $\to$ 입력 방어 $\to$ 캐시/라우팅 $\to$ 런타임 관측의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Prompt Engineering vs Fine-Tuning vs RAG**: 컨텍스트 지시(Prompt), 가중치 업데이트(Fine-Tuning), 외부 지식 검색 주입(RAG).

</details>

| 구분 | 프롬프트 엔지니어링 (Prompt Engineering) | 파인튜닝 (Fine-Tuning) | 검색 증강 생성 (RAG: Retrieval-Augmented) |
|:---|:---|:---|:---|
| **적용 기준** | 응답 톤앤매너, 역할 부여, 간단한 출력 포맷(JSON) 강제 | 특수한 도메인 언어(의료/법률 어조), 고정된 형식 내재화 | 최신 사내 규정, 실시간 뉴스, 자주 변경되는 문서 기반 질의 |
| **핵심 특징** | **모델 가중치 수정 없이 인프롬프트 컨텍스트로 제어** | **도메인 데이터셋으로 모델 가중치를 추가 학습하여 영구 반영** | **벡터 DB 검색으로 관련 문서를 동적 주입하여 환각 방지** |
| **한계** | 컨텍스트 윈도우 토큰 비용 증가 및 복잡한 지식 주입 한계 | 높은 GPU 학습 비용 및 새로운 지식 업데이트 시 재학습 필요 | 검색기(Retriever) 성능에 따른 검색 누락 및 랭킹 오류 위험 |

#### 한줄 요약

- 즉각적 포맷 제어는 프롬프트, 도메인 특화 어조는 파인튜닝, 최신 사실성 보장은 RAG를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **프롬프트 회귀(Prompt Regression)**: 특정 버그를 잡기 위해 프롬프트를 수정했다가 이전에 잘 되던 10가지 질문에서 답변 품질이 급격히 저하되는 부작용.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프롬프트 수정 시 기존 정상 케이스가 망가지는 회귀(Regression) | **CI 파이프라인에 '골든 평가 데이터셋 회귀 테스트' 자동화 강제** | 프롬프트 품질 회귀 100% 방지 |
| LLM 호출 비용 폭증으로 인한 운영 예산 초과 파산 | **`Semantic Caching (Redis)` 및 경량 SLM 모델 우선 라우팅** | LLM API 호출 비용 70% 이상 절감 |
| 비결정적 환각(Hallucination) 답변으로 인한 금융/법률 사고 | **RAG Faithfulness 임계치 미달 시 답변 거부(`I don't know`) 가드레일** | 잘못된 거짓 정보 전파 원천 차단 |

#### 한줄 요약

- 골든 데이터셋 회귀 검증, 시맨틱 캐싱, 환각 방어 가드레일을 통해 LLMOps의 안정성을 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **에이전틱 AI 운영 거버넌스(Agentic AI Operations)**: 단순 질의응답을 넘어 멀티 에이전트 협업과 도구 사용(Tool Calling)까지 안전하게 통제하는 차세대 LLMOps.

</details>

- **LLMOps** 기반 생성형 AI 서비스를 실험실 프로토타입에서 신뢰할 수 있는 엔터프라이즈 프로덕션으로 전환하는 핵심 운영 프레임워크이며, 정량적 Ragas 평가와 입출력 가드레일 및 시맨틱 캐싱을 결합하여 고품질·저비용 AI 운영을 완성해야 함

#### 한줄 요약

- 프롬프트/RAG 버전 관리와 가드레일 및 통계적 평가를 통해 안전하고 경제적인 생성형 AI를 완성
