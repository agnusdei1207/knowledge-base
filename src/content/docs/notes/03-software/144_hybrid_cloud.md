## 미리 알고가기

- **전용 환경**: 프라이빗 클라우드와 기존 데이터센터처럼 조직이 직접 통제하는 실행 환경이다
- **하이브리드 클라우드**: 전용 환경과 퍼블릭 클라우드를 연결해 하나의 업무를 구성한다
- **워크로드 배치**: 데이터 규제·응답 지연·자원 변동에 따라 실행 환경을 선택한다
- **클라우드 버스팅**: 기본 부하를 전용 환경에서 처리하고 초과 부하를 퍼블릭으로 확장한다
- **통합 식별자(Identity, ID)**: ‘아이디’로 읽고 Identity의 머리글자를 딴 표기이며 사용자·서비스 계정을 환경 간 연동하고 같은 접근 정책을 적용한다
- **데이터 동기화**: 환경별 사본의 변경 순서와 일관성 수준을 관리한다
- **경계 지연**: 전용 환경과 퍼블릭 클라우드 사이의 왕복 시간과 전송 대역폭에 좌우된다
- **전용선·가상 사설망(Virtual Private Network, VPN)**: ‘브이피엔’으로 읽고 Virtual·Private·Network의 머리글자를 딴 표기이며 전용 통신 회선과 암호화된 사설 경로로 환경을 연결한다
- **키 관리**: 암호화와 인증에 쓰는 키의 생성·보관·회전·폐기를 통제하는 활동이다
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: ‘에이피아이’로 읽고 세 영문 단어의 머리글자를 딴 표기이며 프로그램이 다른 환경의 서비스 기능을 호출하는 규약이다
- **데이터베이스(Database, DB)·메시지**: ‘디비’는 Database의 관례적 축약 표기이며 데이터베이스는 구조화된 데이터를 저장하고 메시지는 시스템 간 비동기 전달 단위로 쓰인다
- **로그**: 시스템의 요청·오류·변경 사건을 시간순으로 기록한 데이터이다

## Ⅰ. 개요

- **정의/개념**: 전용·퍼블릭 환경의 통합 운영
- **배경/필요성**: 규제 자산은 이전이 어려워 전용·공용 연결 필요

### 쉽게 이해하기 (학습용)
- 전용 환경을 유지하며 공용 자원의 장점을 연결한다

## Ⅱ. 특징

- 규제 데이터는 전용에 두고 업무는 공용에 배치한다.
- 네트워크·신원을 연동해 하나의 서비스로 운영한다.
- 환경 간 호출은 지연·이송 비용·장애 경로를 늘린다.
- 복제 일관성이 전환 시점과 복구 범위를 좌우한다.

### 쉽게 이해하기 (학습용)
- 연결 시 네트워크 지연과 사본의 차이를 관리해야 한다

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 역할 |
|:---|:---|
| 전용·퍼블릭 환경 | 전용은 기존 자산을, 공용은 외부 접점을 제공함 |
| 연결 계층 | 전용 회선과 가상 사설망 등으로 경로를 연결함 |
| 통합 ID·키 관리 | 사용자 계정과 키 정책 등을 환경 간 연동함 |
| 데이터 연계 | 메시지와 복제로 변경 데이터와 결과를 교환함 |
| 통합 운영 | 배포와 로그 등의 정보를 공통 식별자로 연결함 |

```text
  업무분류
      ↓
  환경배치
      ↓
  경계연결
      ↓
  자원연계
      ↓
  성능검증
```

> 요약: 접점과 전용 데이터 사이의 연결 경로가 경계를 형성한다

### 쉽게 이해하기 (학습용)
- 전용 환경과 공용 사이에 통신로와 이동 규칙이 필요하다

## Ⅳ. 원리 및 절차 흐름도

```text
업무분류
   ↓
환경배치
   ↓
경계연결
   ↓
자원연계
   ↓
성능검증
```

| 절차 | 설명 |
|:---|:---|
| **업무분류** | 규제와 부하 변동을 기준으로 분류함 |
| **환경배치** | 전용 환경과 공용의 배치 대상을 정함 |
| **경계연결** | 전용선과 VPN으로 서비스 경로를 연결함 |
| **자원연계** | 통합 ID와 API로 권한과 데이터를 연계함 |
| **성능검증** | 지연과 장애 전환 성능을 측정해 조정함 |

> 요약: 요구 조건으로 환경을 나누고 동기화 결과를 검증한다

### 쉽게 이해하기 (학습용)
- 남길 업무를 나눈 뒤 통로와 자료 방식을 맞춤

## Ⅴ. 종류 및 비교

| 비교축 | 하이브리드 클라우드 | 멀티 클라우드 |
|:---|:---|:---|
| 핵심 특징 | 전용과 공용 환경을 연결해 데이터를 유지함 | 둘 이상의 공용 클라우드를 병행하여 사용함 |
| 업무 배치 | 데이터와 계층을 환경 경계로 분리함 | 업무를 공급자 경계로 분리해 배치함 |
| 데이터 경로 | 전용망으로 전용 환경과 데이터를 교환함 | 공급자 간 복제와 이송 경로를 사용함 |
| 적용 기준 | 민감 시스템은 내부에, 트래픽은 공용에 둘 때 | 특정 제공자 종속 없이 고유 강점을 조합할 때 |
| 주요 위험 | 연결 지연·경계 보안 복잡도 | 공급자 간 운영·데이터 분산 |

> 요약: 전자는 전용 환경과의 결합이고 후자는 공용 간 배치이다

### 쉽게 이해하기 (학습용)
- 하이브리드는 전용·공용 연결을, 멀티 클라우드는 복수 공용 공급자 활용을 다룸

## Ⅵ. 실무 사례

1. 고객 DB는 내부에 두고 API는 공용에 배치한다
2. 초과 작업을 공용으로 확장하고 전송 비용을 확인한다

### 쉽게 이해하기 (학습용)
- 고객 DB와 공용 API 사이의 지연·권한·데이터 경로를 함께 검증한다
- 클라우드 버스팅은 확장 시간과 공용 환경 전송 비용을 함께 확인한다

## Ⅶ. 결론

- 내부 유지 조건·경계 지연·정합성으로 적용 판단

### 쉽게 이해하기 (학습용)
- 공용 자원 이점이 연결 지연과 이중 운영 인력보다 클 때 적용한다
