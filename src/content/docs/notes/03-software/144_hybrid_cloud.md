## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이브리드 클라우드(Hybrid Cloud)**: 온프레미스 프라이빗 인프라와 공용 퍼블릭 클라우드를 전용회선(Direct Connect) 또는 VPN으로 연결하여 단일 인프라처럼 운영하는 모델.
- **Data Sovereignty(데이터 주권)**: 금융 원장, 개인정보 등 민감 데이터를 자국 내 폐쇄망에 보관해야 하는 법적 규제 요건.

</details>

- 정의/개념: 기업의 온프레미스 프라이빗 클라우드와 **공용 퍼블릭 클라우드를 전용망으로 상호 연계하여 보안 통제와 확장 탄력성을 양립**하는 하이브리드 인프라
- 배경/필요성: 핵심 원장의 외부 반출 불가 규제 제약 및 **온프레미스 인프라의 트래픽 급증 수용 불가 한계**

#### 한줄 요약
- 하이브리드는 규제와 탄력성을 동시에 얻는 대신 두 환경을 잇는 전용망이 새로운 단일 장애점이자 지연 요인이 되므로, 경계를 지나는 호출 횟수를 줄이는 설계가 성능의 관건이 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Cloud Bursting**: 평시에는 사내 IDC를 사용하다가 트래픽 급증 시 퍼블릭 클라우드로 연산 자원을 동적으로 임차하여 확장하는 기법.
- **Direct Connect & VPN**: BGP 라우팅 기반 전용회선과 IPsec VPN 암호화 터널을 결합한 고속 사설 연결망.

</details>

- 금융/개인정보 등 핵심 자산을 사내에 격리하는 **강력한 데이터 주권(Data Sovereignty)**
- 피크 타임 트래픽 급증 시 퍼블릭으로 자원을 동적 임차하는 **클라우드 버스팅(Cloud Bursting)**
- Direct Connect 및 IPsec VPN 전용 암호화 통로를 통한 **보안 통신 인프라 완비**

#### 한줄 요약
- 프라이빗의 데이터 통제력과 퍼블릭의 탄력성을 전용선으로 연결하여 결합한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하이브리드 3계층**: Private IDC(코어 원장), Transit Gateway(전용선/VPN 연계), Public VPC(대외 API/캐시).

</details>

```text
[하이브리드 클라우드 계층 아키텍처 구조]
|-- Private IDC (코어 뱅킹 원장 DB, 개인정보, 폐쇄망 레거시 시스템)
|   `-- [Dedicated Direct Connect (10Gbps) + IPsec VPN Backup]
|-- Network Hub (AWS Transit Gateway: BGP 동적 라우팅 및 암호화 터널)
`-- Public Cloud (AWS / Azure Public VPC)
    |-- Frontend / API Gateway (EKS 오토스케일링 웹/앱)
    `-- Caching Layer (Redis Cluster: 온프레미스 원장 쿼리 부하 차단)
```

선의 의미: 계층 및 프라이빗의 민감 데이터와 퍼블릭의 대외 애플리케이션이 전용망과 게이트웨이를 통해 상호 통신하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 프라이빗 클라우드 | 규제 데이터의 **폐쇄망 통제** |
| 퍼블릭 클라우드 | 대외 서비스의 **탄력적 확장** |
| 전용회선·VPN | 양 환경의 **저지연 암호화 연결** |
| 통합 IAM·거버넌스 | 계정과 **권한 정책 단일화** |

#### 한줄 요약
- 전용회선과 Transit Gateway가 공용 인터넷 경유를 대신해 규제 데이터를 폐쇄망 밖으로 내보내지 않고도 퍼블릭 자원을 붙이고, 통합 IAM이 환경마다 따로 두던 계정과 권한 정책을 하나로 대신 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **하이브리드 쿼리 처리 5단계**: 대외 요청 접수 $\to$ 퍼블릭 캐시 검사 $\to$ 전용선 암호화 호출 $\to$ 프라이빗 DB 처리 $\to$ 결과 반환/캐시 갱신.

</details>

```text
대외 사용자의 금융 서비스 요청 접수 (퍼블릭 웹/앱)
        │
   [퍼블릭 캐시 확인] 퍼블릭 Redis 캐시를 조회하여 단순 조회는 온프레미스 호출 없이 즉시 반환
        │ (Cache Miss 또는 원장 갱신 트랜잭션 발생)
   [전용선 암호화 전송] AWS Direct Connect 전용선(Transit Gateway)을 통해 온프레미스로 전달
        │
   [프라이빗 원장 처리] 사내 폐쇄망 코어 DB에서 ACID 원장 트랜잭션 안전하게 실행
        │
   [캐시 갱신] 처리 결과를 퍼블릭 API 서버의 Redis 캐시에 반영
        │
   최종 사용자에게 안전하고 신속하게 트랜잭션 완료 응답 반환
```

#### 한줄 요약
- 퍼블릭 앞단 캐시가 걸러내는 만큼 전용선을 건너는 호출이 줄어들므로, 하이브리드의 응답 시간은 프라이빗의 처리 속도가 아니라 경계를 넘는 빈도가 좌우한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Pure Public vs Pure Private vs Hybrid**: 완전 위탁(Public), 완전 독점(Private), 전략적 융합(Hybrid).

</details>

| 비교 항목 | 순수 퍼블릭 클라우드 (Pure Public) | 순수 프라이빗 클라우드 (Pure Private) | 하이브리드 클라우드 (Hybrid) |
|:---|:---|:---|:---|
| 데이터 주권 및 보안 | CSP 보안 준수 (폐쇄망 제약) | **사내 전용 자원, 완벽한 물리 통제** | **보안 데이터는 내부, 대외 앱은 외부에 분산** |
| 인프라 확장 탄력성 | **무제한 즉각 오토스케일링** | 물리적 장비 증설 필요로 한계 | **평시 프라이빗 + 피크 시 클라우드 버스팅** |
| 인프라 투자 비용 | **초기 비용 제로, 종량제(OpEx)** | **초기 막대한 하드웨어 투자(CapEx)**| **CapEx와 OpEx의 최적 절충** |
| 최적 적용 분야 | **스타트업, 일반 웹/모바일 서비스**| **국방, 최고 보안 정부 행정망** | **금융 코어뱅킹, 헬스케어, 엔터프라이즈**|

#### 한줄 요약
- 완전 위탁은 퍼블릭, 완전 독점은 프라이빗, 규제와 확장의 공존은 하이브리드를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Split-Brain Risk**: 온프레미스와 퍼블릭 간 전용선 단선 시 양쪽 DB가 독립적으로 쓰기를 수행하여 데이터 정합성이 파괴되는 위험.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Direct Connect 전용선 물리적 단선 사고 발생 | **BGP 라우팅 기반 IPsec VPN 자동 백업 경로(Backup) 이중화** | 네트워크 무중단 자동 절체(Failover) |
| 퍼블릭-프라이빗 간 잦은 네트워크 호출로 레이턴시 급증 | **퍼블릭 영역 캐싱 계층(Redis) 및 Read Replica 배치** | 전용선 왕복 트래픽 80% 이상 절감 |
| 온프레미스 AD와 클라우드 IAM 계정 불일치 | **Azure AD / Okta SSO 기반 SAML/OIDC 계정 연동 단일화** | 통합 접근 통제 및 권한 관리 |
| 단선 발생 시 양쪽 독립 쓰기로 인한 데이터 오염 | **단일 마스터(Single-Master) 원칙 및 장애 시 읽기 전용 전환** | 스플릿 브레인(Split-Brain) 원천 차단 |

#### 한줄 요약
- 전용선 이중화, 퍼블릭 캐시 계층화, SSO 계정 통합, 단일 마스터 원칙으로 안정성을 보장한다.

## Ⅶ. 결론

- 금융, 공공, 의료 등 고도의 규제 산업군에서 디지털 금융 혁신을 가능하게 하는 **실질적인 엔터프라이즈 클라우드 표준 전환 모델**로 확립되었으며, 실무 구축 시에는 **전용선 단선 장애를 방어하는 Direct Connect + IPsec VPN 다중화, 전용선 트래픽 병목을 완화하는 퍼블릭 인메모리 캐싱(Redis), 양 환경 간 계정 거버넌스를 일원화하는 Okta/Azure AD SSO 연동, 단선 시 데이터 충돌을 차단하는 단일 마스터(Single-Master) 트랜잭션 원칙**을 결합하여 무결점 보안과 고성능 서비스 연속성을 완성

#### 한줄 요약
- 하이브리드 클라우드는 프라이빗의 데이터 통제력과 퍼블릭의 무제한 탄력성을 융합하여 규제와 혁신을 동시에 만족시키는 핵심 인프라 모델이다.
