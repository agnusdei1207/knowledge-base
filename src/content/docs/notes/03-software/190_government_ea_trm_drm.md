## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Government EA Reference Model (범정부 전사 아키텍처 참조모형)**: 수많은 국가/공공기관이 각자 다른 용어와 구조로 시스템을 구축하는 것을 막기 위해, 범정부 차원에서 업무, 데이터, 서비스, 기술, 성과를 표준화된 분류 체계(Taxonomy)로 통일한 템플릿 세트.
- **Interoperability (상호운용성)**: 국세청 시스템과 행정안전부 시스템이 막힘없이 데이터를 주고받을 수 있도록, 기술 표준(TRM)과 데이터 표준(DRM)을 일치시켜 호환성을 보장하는 성질.
- **Reference Model (참조모형)**: "우리가 새로 만드는 시스템의 구조는 범정부 표준 분류표의 3-1-2번에 해당한다"라고 매핑(Mapping)할 수 있게 해주는 공통 기준 좌표계.

</details>

- 정의/개념: 공공 정보자산을 5개 공통 축으로 분류하는 **EA 참조모형**
- 배경/필요성: 기관별 명칭•기술 차이로 **중복 개발•연계 장애** 발생

#### 한줄 요약

- 기관마다 다른 이름으로 부르는 업무와 데이터와 기술에 같은 분류 번호를 붙이면 중복과 공유 후보를 함께 찾을 수 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **BRM (Business Reference Model, 업무 참조모형)**: 범정부의 모든 행정 업무를 부처와 상관없이 기능(정책, 지원, 평가 등) 중심으로 분류하여, 어떤 부처가 어떤 일을 하는지 매핑하는 기준.
- **SRM (Service Reference Model, 서비스 참조모형)**: 민원 발급, 결제, 보안 등 업무를 지원하는 IT '서비스 컴포넌트'들을 기능별로 분류하여, 재사용 및 공동 활용(예: 통합 로그인)을 유도하는 기준.

</details>

- **BRM/SRM**: 정부 업무와 이를 지원하는 서비스 컴포넌트를 공통 코드로 분류하여, 부처 간 중복 개발을 막고 '공동 활용(Shared Service)'을 유도.
- **DRM (Data Reference Model, 데이터 참조모형)**: 기관 간 교환되는 정보의 표준 단어, 도메인, 코드, 메타데이터 구조를 통일하여 데이터의 일관성과 상호운용성 보장.
- **TRM (Technical Reference Model, 기술 참조모형)**: 시스템을 구축할 때 사용해야 하는 하드웨어, 소프트웨어, 네트워크, 보안 등의 기술 요소와 인정되는 '국가 표준(KICS 등)'을 분류한 카탈로그.
- **PRM (Performance Reference Model, 성과 참조모형)**: 정보화 투자가 실제 행정 효율 향상이나 대국민 만족도 등에 얼마나 기여했는지 측정하는 공통 평가 지표(KPI) 풀(Pool).

#### 한줄 요약

- 기관 자산을 같은 분류표에 올리면 합칠 기능과 공유할 데이터와 표준으로 전환할 기술이 한눈에 드러난다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **EAMS (Enterprise Architecture Management System)**: 각 기관이 자사의 아키텍처 정보를 범정부 참조모형(BRM, TRM, DRM 등) 분류 코드에 매핑하여 등록하는 중앙 집중식 아키텍처 관리 시스템(범정부 GEAP).

</details>

```text
[범정부 EA 참조모형]
 ├── [BRM | 업무]
 ├── [SRM | Service]
 ├── [DRM | Data]
 ├── [TRM | 기술]
 └── [PRM | 성과]
```

| 구성요소 | 책임 |
|---|---|
| BRM | 기관과 무관한 **업무 기능** 분류 |
| SRM | 재사용 가능한 **Service Component** 분류 |
| DRM | Data 의미•Metadata•**교환 표준** 정의 |
| TRM | Platform•Interface•보안 **기술 표준** 정의 |
| PRM | 투입•산출•결과•영향 **성과지표** 분류 |

#### 한줄 요약

- 참조 모형이 공통 분류표를 제공하고 매핑과 저장소가 기관 자산을 모으면 분석과 거버넌스가 통합할 대상을 결정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **사전 협의 제도**: 공공기관이 새로운 정보화 사업을 발주(RFP 공고)하기 전, 해당 사업이 범정부 EA 참조모형(TRM, DRM 등)을 준수했는지, 다른 기관의 시스템과 중복되지 않는지 정보화 전담 기관(NIA 등)에 심사를 받는 법적 통제 절차.

</details>

```text
[공공기관 (사업 부서)]                                 [범정부 EA 통제 기관]
         │                                                    │
         ├─ 1. 신규 사업 기획 (ISP/ISMP) ────────────────────►│
         │                                                    ├─ 2. 중복성 검토 (BRM/SRM 기반)
         │                                                    │
         ├─ 3. 시스템 아키텍처 및 데이터 설계 (RFP 초안) ────►│
         │                                                    ├─ 4. 표준 준수 검토 (DRM/TRM 기반)
         │                                                    │
         │◄─ 5. (부적합) 재설계 및 매핑 반려 ─────────────────┤
         │                                                    │
         ├─ 6. 아키텍처 보완 (TRM 표준 기술 채택 등) ────────►│
         │                                                    ├─ 7. (적합) 사업 승인 및 예산 배정
         │                                                    │
         │◄─ 8. 프로젝트 발주 및 시스템 구축 (구현 거버넌스) ─┤
```

### 동작 원리

1. **중복 통제 (BRM/SRM)**: 기관이 새 시스템을 만들겠다고 하면, BRM/SRM 분류 코드를 검색하여 다른 부처에 이미 만들어진 동일한 서비스(예: 전자결재)가 있는지 확인하고, 있으면 공동 활용을 지시.
2. **표준 통제 (TRM/DRM)**: 사업 계획서의 아키텍처가 범정부 TRM이 허용하지 않는 비표준 기술을 쓰거나, DRM에 위배되는 데이터 명명 규칙을 쓰면 반려(Reject).
3. **자산 등록 (EA 현행화)**: 구축이 완료되면 최종 산출물을 EAMS에 범정부 참조 코드에 맞춰 다시 매핑하여 등록 (**전사 기준선 갱신 완결**).

#### 한줄 요약

- 기관 자산에 같은 코드를 붙이고 기존 저장소와 대조하면 이름이 달라도 같은 기능과 데이터인 대상을 찾을 수 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Technical Profile (기술 프로파일)**: TRM이 "네트워크 계층에는 이런 기술들이 있다"는 분류라면, 기술 프로파일은 그중에서 "우리 기관은 IPv6와 TLS 1.3을 표준으로 쓴다"라고 콕 집어 확정한 구체적 기술 규격서.

</details>

| 비교 항목 | DRM (데이터 참조모형) | TRM (기술 참조모형) |
|:---|:---|:---|
| **핵심 목적** | **데이터의 의미 통합 및 기관 간 정보 교환(공동 활용) 보장** | **IT 인프라 호환성 확보 및 기술의 노후화(벤더 종속) 방지**|
| **관리 대상** | 데이터 모델, 분류 체계, 메타데이터, 데이터 품질 지표 | S/W, H/W, 네트워크, 보안 플랫폼, 인터페이스 규격 |
| **통제 방식** | 데이터 명명 규칙(표준어 사전) 및 XML/JSON 스키마 통제 | 기술 프로파일 제정 및 비표준 기술 도입 차단 |
| **효과** | 시스템 간 연계 시 **데이터 정합성(일치성) 확보** | 시스템 간 연계 시 **기술적 상호운용성 확보** |

#### 한줄 요약

- DRM은 기관 사이에서 같은 데이터 뜻과 형식을 맞추고 TRM은 그 데이터를 주고받을 기술 규격을 맞춘다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Mapping (매핑)**: 기관 자체적으로 부르는 용어(예: '고객 관리')를 범정부 공통 분류 코드(예: BRM 코드 1-05-02 '민원인 관리')에 연결하여 번역하는 작업으로, 매핑이 잘못되면 EA 분석 전체가 실패함.

</details>

| 3대 EA 실무 난제 | 발생 원인 | 실무 대책 및 해결방안 |
|:---|:---|:---|
| **1. 형식적인 매핑(Mapping) 오류**| 실무자의 EA 이해 부족 및 편의주의 매핑 | **EA 전담 조직(아키텍트)의 매핑 검증 및 가이드라인 훈련**|
| **2. TRM의 기술 노후화 현상** | 기술 변화(클라우드, AI)를 TRM이 못 따라감| **TRM 기술 프로파일의 정기적 개정(Rolling) 및 예외 승인 절차 마련**|
| **3. DRM 표준 위반 시스템 양산**| SI 개발자가 데이터 표준을 무시하고 개발 | **DB 자동 스키마 검증 도구를 통한 현행화 모니터링 강제**|

> 사례: **행정안전부 주도의 범정부 EA 기반 사전협의제도 운영 및 정보화 사업 중복 투자 삭감을 통한 대규모 국가 예산 절감 사례**

#### 한줄 요약

- 기관별 주소 항목은 DRM의 공통 의미와 형식에 매핑하고 교환 인터페이스는 TRM 표준에 대조해야 의미와 전송이 함께 맞는다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **GEAP (범정부 전사아키텍처 포털)**: 모든 공공기관이 자사의 EA 산출물을 BRM/TRM/DRM 등의 분류표에 맞추어 등록하고, 타 기관의 시스템을 검색(공동 활용)할 수 있게 만든 중앙 정부 차원의 통합 시스템.

</details>

- 중복 기능은 **BRM•SRM**으로 통합, 연계 사업은 DRM•TRM 준수

#### 한줄 요약

- 공통 분류표를 등록용으로 끝내지 않고 예산과 사업 심사에 연결해 통합·공유·표준 전환을 결정할 때 가치가 생긴다.
