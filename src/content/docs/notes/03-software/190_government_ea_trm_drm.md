## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **범정부 EA 참조모형 (Government EA Reference Models)**: 모든 공공기관이 일관된 기준에 따라 정보화 자산을 식별·분류·관리할 수 있도록 5대 공통 축인 업무(BRM), 서비스(SRM), 데이터(DRM), 기술(TRM), 성과(PRM)를 표준화한 참조 프레임워크.
- **공공 정보화 중복 투자 및 연계 단절(Public Redundancy & Data Silo Risk)**: 각 정부 부처와 지자체가 상이한 용어와 독자 기술을 사용하여 동일한 시스템을 중복 구축하고 기관 간 데이터 연계가 단절되는 위험.

</details>

- 정의/개념: 공공기관 간 정보자산의 상호운용성과 재사용성을 확보하기 위해 **5대 표준 분류체계(BRM, SRM, DRM, TRM, PRM)를 제공하는 범정부 참조모형**
- 배경/필요성: 정부 부처 및 공공기관별 상이한 용어와 독자적 시스템 구축으로 인한 **기관 간 중복 투자 낭비 및 행정 데이터 연계 불가 위험** 직면

#### 한줄 요약

- 5대 참조모형(BRM/SRM/DRM/TRM/PRM)을 통해 공공 정보화 사업의 중복 투자를 방지하고 기관 간 데이터·기술 상호운용성을 완성

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 참조모형(DRM: Data Reference Model)**: 공공기관 간 교환되는 데이터의 표준 단어, 도메인, 코드, 메타데이터 구조를 통일하는 표준.
- **기술 참조모형(TRM: Technical Reference Model)**: 정보시스템 구축 시 준수해야 하는 하드웨어, 소프트웨어, 네트워크, 보안 기술 표준과 프로파일.

</details>

- 부처와 무관하게 기능 중심으로 행정 업무와 서비스 컴포넌트를 분류하는 **BRM/SRM 기반 중복 통제**
- 공공 데이터 표준 용어 사전과 교환 스키마를 정의하는 **DRM 기반 데이터 정합성 보장**
- 전자정부 표준 프레임워크 및 국가 보안 규격을 강제하는 **TRM 기반 기술 상호운용성 확보** #### 한줄 요약

- 표준화된 분류체계와 공공 사전협의 제도를 결합하여 국가 예산 절감과 데이터 공유를 실현

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **범정부 EA 5대 참조모형 체계**: PRM(성과), BRM(업무), SRM(서비스), DRM(데이터), TRM(기술).

</details>

```text
[ 범정부 EA 5대 참조모형(Reference Models) 계층 구조도 ]

 1. [ 성과 참조모형 (PRM: Performance Reference Model) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • 정보화 투자 성과 지표 (투입 ➔ 산출 ➔ 결과 ➔ 영향 지표)   │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 2. [ 업무 참조모형 (BRM) ]     │  [ 서비스 참조모형 (SRM) ]
    • 정부 기능 분류 (정책/지원) │  • 재사용 서비스 컴포넌트 (공통 로그인)
    └────────────────────────────┼────────────────────────────────┘
                                 │
                                 ▼
 3. [ 데이터 참조모형 (DRM) ]   │  [ 기술 참조모형 (TRM) ]
    • 공공 표준 단어/도메인 사전 │  • 인프라, 플랫폼, 보안 표준 프로파일
    • 데이터 모델, 교환 스키마   │  • 전자정부 표준 프레임워크
    └────────────────────────────┴────────────────────────────────┘
                                 │
                                 ▼
 4. [ 범정부 정보기술아키텍처 지원시스템 (GEAP & 사전협의제도) ]
```

선의 의미: 성과(PRM) 아래 업무(BRM)와 서비스(SRM)를 정의하고, 데이터(DRM)와 기술(TRM)이 이를 지원하여 GEAP 포털에서 통제되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 업무 참조모형 (BRM) | 정부 기능과 행정 업무를 부처에 독립적으로 **기능별 계층 구조로 표준 분류** |
| 서비스 참조모형 (SRM) | 인증, 결제, 민원 발급 등 **재사용 가능한 공통 응용 서비스 컴포넌트 분류** |
| 데이터 참조모형 (DRM) | 데이터 분류 체계, **표준 단어/용어 사전, 메타데이터 교환 스키마 표준 정의** |
| 기술 참조모형 (TRM) | 하드웨어, OS, DBMS, 네트워크, 보안의 **표준 기술 프로파일 및 국가 표준 제시** |
| 성과 참조모형 (PRM) | 정보화 투자의 **행정 효율성, 비용 절감, 대국민 서비스 만족도 측정 지표 제공** |

#### 한줄 요약

- BRM, SRM, DRM, TRM, PRM 5대 참조모형이 결합하여 범정부 정보화 표준을 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **범정부 EA 기반 공공 정보화 사전협의 5단계**: 사업 기획 $\to$ BRM/SRM 중복성 심사 $\to$ DRM/TRM 기술 표준 심사 $\to$ 사업 승인 및 발주 $\to$ GEAP 자산 등록 현행화.

</details>

```text
[ 범정부 EA 참조모형 기반 공공 사업 사전협의 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 공공기관: 신규 정보화 사업 계획 수립│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 행안부/NIA: BRM/SRM 기반 중복성 심사│
 ├───────────────────┬────────────────────┤
 │ 중복 발견 (반려)  │ 중복 없음 (통과)   │
 │ • 공동 활용 권고  │ • 다음 단계 진행   │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 행안부/NIA: DRM/TRM 기반 표준 적합성 심사
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 사전협의 승인 및 기재부 예산 확정 발주│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 구축 완료 후 산출물 GEAP 등록(현행화)│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 사업 기획: 공공기관이 신규 정보화 사업 계획서(ISMP)를 작성하여 범정부 EA 시스템(GEAP)에 제출.
2. 중복 심사: 심사 기관이 BRM/SRM 코드를 조회하여 타 부처에 이미 구축된 동일 서비스가 있는지 검토(중복 시 반려).
3. 기술 심사: 제안된 시스템이 범정부 DRM(표준 단어 사전)과 TRM(전자정부 표준프레임워크, CSAP 클라우드)을 준수하는지 검증.
4. 예산 확정: 사전협의 적합 판정을 받은 사업에 한하여 예산이 배정되고 조달청을 통해 공식 입찰 발주.
5. 자산 현행화: 시스템 구축이 완료되면 최종 소프트웨어 및 인프라 명세를 GEAP에 등록하여 국가 IT 자산을 갱신.

#### 한줄 요약

- 사업 기획 $\to$ 중복성 심사 $\to$ 기술 표준 심사 $\to$ 예산 확정 $\to$ GEAP 현행화의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DRM vs TRM**: 데이터 의미 및 스키마 표준(DRM)과 하드웨어/소프트웨어 기술 프로파일 표준(TRM).

</details>

| 구분 | 데이터 참조모형 (DRM: Data Reference Model) | 기술 참조모형 (TRM: Technical Reference Model) |
|:---|:---|:---|
| **적용 기준** | 기관 간 행정 데이터 공동 활용, 마이데이터 연계, 공공 DB 구축 | 공공 클라우드 전환, 전자정부 프레임워크 적용, 인프라 표준화 |
| **핵심 특징** | **표준 단어/도메인/코드 사전, 메타데이터 구조, XML/JSON 스키마** | **서비스 접근, 플랫폼, 소프트웨어, 네트워크, 보안 기술 프로파일** |
| **한계** | 기관 고유의 특수 데이터 도메인까지 100% 포괄하기 어려움 | 급변하는 민간 신기술(생성형 AI 등)의 적시 반영 지연 한계 |

#### 한줄 요약

- 데이터의 의미와 공유는 DRM, 인프라와 소프트웨어 기술 규격은 TRM을 준수

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **참조모형 매핑 오류(Mapping Error)**: 기관 실무자가 범정부 분류 코드의 의미를 오해하여 엉뚱한 BRM/TRM 코드로 등록함으로써 전사 검색과 통제가 왜곡되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 실무자의 자의적·형식적 매핑으로 범정부 EA 자산 검색 신뢰도 저하 | **전문 아키텍트 주관의 매핑 검증 프로세스 및 가이드라인 정례 교육** | 매핑 정합성 및 검색 정확도 95% 이상 달성 |
| 최신 클라우드 및 AI 기술이 TRM에 반영되지 않아 사업 지연 초래 | **TRM 기술 프로파일의 주기적 개정(Rolling) 및 '신기술 신속 도입 트랙' 운영** | 공공 디지털 혁신 속도 확보 |
| SI 구축 사업자가 범정부 데이터 표준(DRM)을 무시하고 자체 DB 설계 | **감리 단계에서 '행정기관 데이터 표준 준수 여부'를 필수 검수 항목 지정** | 기관 간 데이터 연계 100% 보장 |

#### 한줄 요약

- 매핑 검증 강화, 기술 프로파일 정기 갱신, 감리 검수 강제를 통해 범정부 EA의 실효성을 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **디지털플랫폼정부(DPG) 상호운용성 기반**: 5대 참조모형을 기반으로 민간과 공공이 하나의 플랫폼처럼 연결되는 차세대 정부 혁신 아키텍처.

</details>

- **범정부 EA 참조모형(TRM/DRM)** 은 국가 디지털 인프라의 중복을 배제하고 초연결 상호운용성을 달성하는 표준 가이드라인이며, 사전협의제도와 GEAP 현행화를 지속 강화하여 지능형 디지털플랫폼정부를 완성해야 함

#### 한줄 요약

- 5대 참조모형과 사전협의 거버넌스를 통해 중복 투자를 차단하고 공공 상호운용성을 완성
