## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **관계형 데이터베이스(Relational Database)**: 데이터를 릴레이션으로 표현하고 키•제약조건•관계 연산으로 구조와 무결성을 관리하는 데이터 관리 시스템이다.
- **데이터 중복(Data Redundancy)**: 같은 사실이 여러 위치에 반복 저장된 상태다.
- **참조 불일치(Referential Mismatch)**: 외래키가 존재하지 않는 대상을 가리키는 오류다.

</details>

- 정의/개념: **관계형 데이터베이스** 는 데이터를 릴레이션으로 표현하고 키•제약조건•관계 연산으로 구조와 무결성을 관리하는 **데이터 관리 시스템**
- 배경/필요성: 응용 코드만의 검증은 동시 변경에서 **중복•참조 불일치 통제 한계**

#### 한줄 요약

- 릴레이션•키•제약 기반 **데이터 관계•무결성 관리**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **집합 연산**: 튜플 순서와 중복에 의존하지 않고 관계를 처리하는 연산 방식이다.
- **선언형 질의**: 원하는 결과를 기술하면 데이터베이스 엔진이 실행 방법을 선택하는 방식이다.
- **무결성 강제**: 도메인•개체•참조 규칙을 위반하는 변경을 데이터베이스가 거부하는 통제이다.

</details>

- **집합 연산**: 튜플 순서와 중복에 비의존
- **선언형 질의**: 엔진이 실행 계획을 선택
- **무결성 강제**: 도메인•개체•참조 위반 거부

#### 한줄 요약

- 집합 연산•선언형 질의•**무결성 강제**

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **릴레이션(Relation)**: 속성과 중복 없는 튜플 집합으로 정의되는 논리 구조이다.
- **기본키(Primary Key)**: 릴레이션의 튜플을 고유하게 식별하는 속성 집합이다.
- **외래키(Foreign Key)**: 다른 릴레이션의 키를 참조하는 속성 집합이다.
- **무결성 제약조건(Integrity Constraint)**: 데이터가 허용된 상태를 유지하도록 변경을 통제하는 규칙이다.
- **구조화 질의 언어(Structured Query Language, SQL)**: 관계형 데이터의 정의와 조회 및 변경을 선언하는 언어다.
- **SQL 처리기(SQL Processor)**: SQL 질의를 해석하는 구성요소다.
- **옵티마이저(Optimizer)**: 예상 비용이 낮은 실행 계획을 선택하는 구성요소다.

</details>

```text
[SQL 처리기•옵티마이저]
          |
 [무결성 제약조건] --- [기본키•외래키]
          |
      [릴레이션]
```

선의 의미: SQL 처리기•옵티마이저와 무결성 제약조건의 선은 질의 실행과 변경 후보 검증의 결합 관계, 무결성 제약조건과 릴레이션의 선은 도메인•개체•참조 규칙 강제 관계, 기본키•외래키와 무결성 제약조건의 선은 튜플 식별•참조 관계 정의를 검사 규칙으로 제공하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 릴레이션 | **속성•튜플 집합** 의 논리 구조 제공 |
| 기본키•외래키 | 튜플의 **식별•참조 관계** 정의 |
| 무결성 제약조건 | **도메인•개체•참조 규칙** 검사 |
| SQL 처리기•옵티마이저 | **비용 기반 실행 계획** 선택 |

#### 한줄 요약

- 처리기•제약•키•**릴레이션 구조**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **실행 계획•예상 비용**: 통계로 선택한 접근 방법과 조인 순서 및 예측 자원 비용이다.
- **관계 연산•변경 후보 튜플**: 질의가 처리하거나 저장 전 검증할 행 집합이다.
- **검증된 관계 연산**: 키•참조•도메인 규칙을 통과해 저장소와 인덱스에서 수행하는 작업이다.
- **SQL 구문•의미 분석**: 선언문을 해석하고 릴레이션•속성•연산의 유효성을 확인하는 동작이다.
- **비용 기반 실행 계획 선택**: 통계로 접근 방법과 조인 순서를 비교해 예상 비용이 낮은 계획을 고르는 동작이다.
- **관계 연산 실행**: 선택한 계획에 따라 저장소와 인덱스에서 조회•결합•변경 후보를 처리하는 동작이다.
- **무결성 검증•결과 확정**: 변경은 키•도메인•참조 규칙을 검사하고 조회는 결과 행을 반환하는 동작이다.

</details>

```text
[SQL 문•매개변수]
        |
        v
+--------------------------------+
| 1. SQL 구문•의미 분석         |
+--------------------------------+
        |
        v
+--------------------------------+
| 2. 비용 기반 실행 계획 선택   |
+--------------------------------+
        |
        v
+--------------------------------+
| 3. 관계 연산 실행             |
+--------------------------------+
        |
        v
+--------------------------------+
| 4. 무결성 검증•결과 확정      |
+--------------------------------+
        |
   +----+----+
   | 조회    | 변경
   v         v
[결과 행] [제약 통과 후 커밋]
```

**동작 원리**

1. **SQL 구문•의미 분석**: 선언과 객체 유효성 확인
2. **비용 기반 실행 계획 선택**: 접근•조인 순서 결정
3. **관계 연산 실행**: 저장소•인덱스에서 계획 수행
4. **무결성 검증•결과 확정**: 조회 반환•변경 커밋

> 요약: SQL의 선언을 비용 기반 계획으로 실행하고 변경 시 무결성 제약을 강제

#### 한줄 요약

- SQL 해석•최적화•연산•**무결성 검증 흐름**

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **비관계형 데이터베이스(Not Only SQL, NoSQL)**: 키-값•문서•열•그래프 등 목적별 모델을 사용하는 범주이다.

</details>

| 데이터 모델 관점 | 관계형 데이터베이스 | 비관계형 데이터베이스 |
|:---|:---|:---|
| 적용 기준 | **복합 관계•트랜잭션•무결성** 중심 | **특정 접근 패턴•유연한 모델** 중심 |
| 핵심 특징 | **테이블•관계•선언형 SQL** | **키-값•문서•열•그래프** 모델 |
| 한계 | **분산 조인•샤딩 설계** 복잡도 | 제품별 **일관성•제약 기능** 차이 |

> 요약: 관계형은 스키마•제약을 엔진이 관리

#### 한줄 요약

- 복합 관계는 관계형, 특정 접근은 **비관계형**

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **안정 후보키(Stable Candidate Key)**: 값이 쉽게 바뀌지 않는 고유 식별자 후보다.
- **업무 유일 제약(Business Unique Constraint)**: 업무 값의 중복을 막는 제약조건이다.
- **참조 무결성(Referential Integrity)**: 외래키 대상의 존재를 보장하는 성질이다.
- **변경 정책(Change Policy)**: 참조 대상 삭제와 갱신 시 동작을 정한 규칙이다.
- **측정된 병목만 비정규화**: 실제 성능 측정으로 확인한 반복 조인 구간에 한해 중복을 허용하고 일관성 통제를 함께 두는 원칙이다.
- **질의 패턴(Query Pattern)**: 실제 데이터 접근과 필터 조건의 반복 형태다.
- **선택도(Selectivity)**: 조건으로 걸러지는 행 비율이다.
- **통계(Statistics)**: 데이터 값과 분포를 요약한 정보다.
- **원자성을 지키는 최소 범위**: 함께 성공하거나 실패해야 하는 작업만 하나의 트랜잭션에 넣어 잠금 보유 시간을 줄이는 경계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 변경 가능한 업무 값을 기본키로 써 연쇄 수정 발생 | **안정 후보키•업무 유일 제약** 분리 | **연쇄 키 수정** 방지 |
| 외래키 없이 응용 코드만 검사해 고아 데이터 생성 | **참조 무결성•변경 정책** 명시 | **고아 데이터 생성** 차단 |
| 과도한 정규화로 반복 조인과 조회 지연 증가 | **측정된 병목만 비정규화** | **무결성•조회 성능** 균형 |
| 낮은 선택도 인덱스까지 추가해 쓰기•저장 비용 증가 | **질의•선택도•통계 기반 인덱스** 운영 | **쓰기•저장 비용** 감소 |
| 긴 트랜잭션이 잠금을 오래 보유해 경합•교착 증가 | **원자성을 지키는 최소 범위** 로 축소 | **잠금 경합•교착** 감소 |

> 적용 사례: 외래키는 존재하지 않는 계좌를 참조하는 이체 내역의 저장을 거부

#### 한줄 요약

- 키•참조•인덱스•**트랜잭션 경계 통제**
