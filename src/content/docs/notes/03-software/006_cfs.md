## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CFS(Completely Fair Scheduler)**: 가중 가상 실행시간을 기준으로 CPU 몫을 배분하는 Linux 공정 스케줄링 모델.
- **vruntime(Virtual Runtime)**: 프로세스의 실제 물리 CPU 점유 시간을 Nice 가중치(Prio_to_weight) 표에 역비례 곱산 보정한 누적 가상 실행 시간.
- **cfs_rq (CFS Run-Queue)**: Linux 커널 내에서 실행 가능(Task_Running) 상태의 `sched_entity` 노드들을 vruntime 기준 오름차순으로 정렬 보관하는 Red-Black Tree 큐.

- **레드-블랙 트리(Red-Black Tree)**: CFS에서 실행 가능한 태스크들을 가상 실행 시간(vruntime) 기준으로 정렬 유지하여 $O(\log N)$ 삽입/삭제를 보장하는 자가 균형 이진 탐색 트리.
- **가상 마감시각(Virtual Deadline / EEVDF)**: 리눅스 최신 커널(6.6+)의 EEVDF 스케줄러에서 태스크의 지연(Lag)을 보상하기 위해 vruntime에 비례하여 산출하는 스케줄링 우선순위 기준점.
</details>

- 정의/개념: 프로세스의 실행 시간을 Nice 가중치 기반 **vruntime**으로 보정 환산하여, 이상적인 멀티태스킹 하드웨어를 소프트웨어적으로 정밀 모사하는 **CFS(Completely Fair Scheduler)**
- 배경/필요성: 휴리스틱 작업 분류는 부하 변화 시 **공정한 CPU 몫 산정 곤란**

#### 한줄 요약

- 가중 CPU 사용량인 vruntime이 가장 작은 태스크를 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **sched_latency**: 모든 실행 프로세스가 적어도 1회 이상 CPU를 점유할 수 있도록 보장하는 전체 스케줄링 순환 보장 주기 (기본값: 6ms ~ 24ms).
- **min_granularity**: 프로세스가 한 번 CPU를 선점 디스패치 받았을 때 문맥 전환(Context Switch) 전 최소한 보장받는 연속 실행 시간 하한 (기본값: 0.75ms ~ 3ms).
- **prio_to_weight**: Nice 값(-20 ~ +19, 총 40단계)을 1.25의 거듭제곱 비율 기반 CPU 점유 가중치 수치(15 ~ 88761)로 변환해 둔 커널 매핑 테이블.

</details>

- 고정된 타임 슬라이스(Time Slice) 부재 및 **sched_latency**와 **prio_to_weight** 가중치 기반 동적 할당
- 가장 왼쪽($O(\log N)$) 노드를 선택하기 위한 자가 균형 이진 탐색 **Red-Black Tree(cfs_rq)** 알고리즘 적용
- 과도한 문맥 전환을 줄이는 **min_granularity** 실행 하한

#### 한줄 요약

- 실행 태스크가 증가해도 최소 세분도를 실행 구간 하한으로 적용한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **sched_entity**: Linux 커널 Task Struct 구조체 내에 포함되어 vruntime 및 cfs_rq Red-Black Tree 노드 포인터를 관리하는 스케줄링 단위 객체.

</details>

```text
[스케줄링 개체]
        |
[CFS 실행 큐]
        |
[CFS 스케줄러]
        |
      [CPU]
```

선의 의미: `sched_entity` 객체가 cfs_rq(Red-Black Tree)에 vruntime 순으로 바인딩되어 CFS 스케줄러에 의해 최저 노드가 선택된 후 CPU 코어에 인가되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 스케줄링 개체 (`sched_entity`) | 프로세스별 누적 **vruntime**, 가중치 메타데이터 및 RB-Tree 핑거 보관 |
| CFS 실행 큐 (`cfs_rq`) | `rb_leftmost` 포인터를 통해 가장 적은 **vruntime** 노드를 $O(1)$ 직결 레퍼런스 |
| CFS 스케줄러 | **vruntime** 증가량 산출 및 선점(Preemption) 판정, RB-Tree 밸런싱 재배치 |
| CPU 코어 | 선택된 프로세스의 명령어 연산 및 하드웨어 타이머 틱(Tick) 상주 연동 |

$$\text{vruntime 증가량} = \text{실제 실행시간} \times \frac{\text{NICE\_0\_LOAD (1024)}}{\text{prio\_to\_weight[Nice]}}$$

#### 한줄 요약

- 스케줄링 개체, CFS 실행 큐, CFS 스케줄러가 vruntime 정렬과 최솟값 선택을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **rb_leftmost**: Red-Black Tree의 가장 좌측 트래버스 노드로, 최저 vruntime을 지녀 즉시 $O(1)$ 시간 복잡도로 디스패치 대상을 지칭하는 포인터.

</details>

```text
┌──────────── CFS 배분 반복 ────────────┐
│ 1. 최소 vruntime 개체 선택            │
│          │                             │
│          ▼                             │
│ 2. 가중 실행 구간 산정                │
│          │                             │
│          ▼                             │
│ 3. 태스크 디스패치•실행               │
│          │                             │
│          ▼                             │
│ 4. vruntime 가중 누적                 │
│          │                             │
│          ▼                             │
│ 5. 실행 큐 재삽입                     │
│          └── 최소 vruntime 선택으로 반복
└───────────────────────────────────────┘
```

### 동작 원리

1. 최소 vruntime 개체 선택: cfs_rq 내 **rb_leftmost** 포인터가 가리키는 최소 vruntime 노드 래칭.
2. 가중 실행 구간 산정: **prio_to_weight** 가중치 지수 기반 동적 Time Slice 계산 인가.
3. 태스크 디스패치·실행: 사용자 모드 전환 및 실제 CPU 코어 명령어 연산 구동.
4. vruntime 가중 누적: 하드웨어 타이머 틱 발생 시 실제 실행 시간에 가중치 역비례식을 적용하여 **vruntime** 갱신.
5. 실행 큐 재삽입: 갱신된 vruntime을 바탕으로 Red-Black Tree 내 위치 재정렬 인가.

#### 한줄 요약

- 최소 vruntime 개체 선택과 vruntime 가중 누적 및 실행 큐 재삽입을 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **EEVDF(Earliest Eligible Virtual Deadline First)**: Linux 6.6 커널부터 CFS를 대체하여 프로세스의 Latency 제약(Virtual Deadline)까지 결합 보장하는 차세대 완전 공정 스케줄러.

</details>

| 비교 항목 | CFS (Completely Fair Scheduler) | $O(1)$ Scheduler (구버전) | EEVDF (차세대 Linux 6.6) |
|:---|:---|:---|:---|
| 핵심 자료구조 | **Red-Black Tree (cfs_rq)** | Active/Expired Priority Arrays | Red-Black Tree + Virtual Deadline |
| 공정성 기준 | **vruntime** (가중치 보정 가상시간) | 고정 Priority 및 Heuristic 회계 | vruntime + **Lag / Virtual Deadline** |
| 타임 슬라이스 | 동적 가변 (**sched_latency** 기반) | 정적 고정 타임 슬라이스 | 동적 가변 + Latency 수용 |
| 선택 기준 | 최소 **vruntime** | 고정 우선순위 배열 | 적격성•**가상 마감시각** |

#### 한줄 요약

- CFS의 가중 몫과 RR의 동일 할당량이라는 선택 기준 차이가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Autogroup / Cgroups**: CPU 자원을 프로세스 단위가 아닌 CGroups 그룹 단위로 계층 구조화하여 공정 몫(Group Share)을 할당하는 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프로세스 수가 수천 개로 폭증하여 문맥 전환 지연 발생 | **sysctl (kernel.sched_min_granularity_ns)** 하한 튜닝 | 문맥 전환 지연 억제 |
| 특정 대화형 서비스가 CPU-bound 프로세스에 밀려 지연 | **Nice** 값 조정(-10) 또는 **sched_wakeup_granularity_ns** 선점 수용 | 대화형 응답성 확보 |
| 특정 멀티스레드 사용자의 CPU 독점 | **cgroup cpu.weight**로 계층별 몫 설정 | 그룹 간 CPU 몫 분리 |

> 사례: Linux 6.1 커널 상의 **CFS cfs_rq** 튜닝 및 **Cgroups v2** 기반 K8s Pod CPU 쿼터 배분

#### 한줄 요약

- 웹•배치 작업에 nice 값과 그룹 스케줄링별 CPU 몫을 배분한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CFS 스케줄러 적용 기준(CFS Adoption & Tuning Criteria)**: 프로세스 런타임 수량, Nice 가중치 구조, 반응 지연(Latency) 허용 수치에 기반한 튜닝 체계.

</details>

- 비례 CPU 몫은 **CFS 계열**, 지연 민감 작업은 **EEVDF 정책** 검토

#### 한줄 요약

- CPU 몫과 꼬리 응답 목표로 가중치•깨움 세분도를 결정한다.
