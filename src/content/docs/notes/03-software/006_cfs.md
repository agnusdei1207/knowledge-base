## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 실행 시간(vruntime)**: 프로세스의 실제 CPU 점유 시간에 nice 우선순위 역가중치를 곱하여 산출한 공정 배분 기준 척도.
- **동적 자원 지분 불균형(Dynamic Resource Imbalance)**: 작업 수 변동 시 고정 타임 퀀텀 구조에서 우선순위별 CPU 할당 비율이 왜곡되는 현상.

</details>

- 정의/개념: 가상 실행 시간(**vruntime**)을 레드-블랙 트리로 관리하여 CPU 점유량이 가장 적은 프로세스를 우선 디스패치하는 리눅스 공정 스케줄링 기법
- 배경/필요성: 기존 $O(1)$ 스케줄러의 복잡한 휴리스틱 판정 오판 및 부하 변동 시 **동적 CPU 자원 지분 불균형과 인터랙티브 반응 지연** 직면

#### 한줄 요약

- CPU 점유량이 가장 적은 프로세스(최소 vruntime)를 우선 실행하여 공정 배분을 보장하는 리눅스 기본 스케줄러

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스케줄 지연 시간(sched_latency)**: 준비 큐의 모든 프로세스가 최소 1회 CPU를 할당받도록 커널이 보장하는 전체 순환 주기.
- **최소 보장 시간(min_granularity)**: 프로세스 수가 많아져 몫이 지나치게 작아질 때 문맥 전환 오버헤드가 실행 시간을 초과하지 않도록 보장하는 최소 실행 시간 하한.
- **나이스 값 가중치(prio_to_weight)**: 나이스 값(-20~19)을 CPU 점유 가중치 수치(15~88761)로 변환하는 커널 변환표.

</details>

- 고정 타임 슬라이스 없이 **sched_latency**를 **나이스 값 가중치** 비율로 분할하여 동적 할당
- **레드-블랙 트리**에서 최소 vruntime 프로세스를 O(log n) 시간에 선정
- 프로세스 수 증가로 몫이 축소될 때 **최소 보장 시간** 적용으로 문맥 전환 오버헤드 억제

#### 한줄 요약

- 가중치 기반 동적 타임 슬라이스 분배 및 레드-블랙 트리 기반 O(log n) 우선순위 선정으로 공정성 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **sched_entity**: 프로세스의 vruntime·레드-블랙 트리 포인터·실행 통계를 보관하는 CFS 전용 경량 스케줄링 단위 구조체.
- **cfs_rq**: 실행 가능한 프로세스의 sched_entity를 vruntime 순으로 관리하는 CPU 코어별 CFS 준비 큐.

</details>

```text
[ CFS 내부 구조 ]
cfs_rq (CPU 코어별 CFS 준비 큐)
└─ 레드-블랙 트리 (vruntime 오름차순 정렬)
    ├─ sched_entity A (vruntime 최소 → 다음 실행)
    ├─ sched_entity B
    └─ sched_entity C
커널 스케줄러
├─ 최소 vruntime 노드(leftmost) 선정
├─ 동적 타임 슬라이스 계산
│   └─ sched_latency × (가중치 / 전체 가중치 합)
└─ min_granularity 하한 보정
```

선의 의미: 가지(`├─`, `└─`)는 CFS 준비 큐 내 sched_entity 소유 관계 및 스케줄러의 선정·계산 흐름

| 구성요소 | 책임 |
|:---|:---|
| cfs_rq | **vruntime** 순 정렬로 다음 실행 프로세스 보관 |
| sched_entity | 프로세스별 **vruntime**·트리 포인터 관리 |
| 레드-블랙 트리 | 최소 **vruntime** 프로세스를 O(log n)에 선정 |
| 동적 타임 슬라이스 계산기 | **sched_latency**·**나이스 값 가중치**로 몫 산출 |

#### 한줄 요약

- cfs_rq의 레드-블랙 트리에서 최소 vruntime 프로세스를 선정하고 가중치 비례로 실행 시간을 할당

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **leftmost 노드**: 레드-블랙 트리에서 vruntime이 가장 작은 맨 왼쪽 노드로, CFS의 다음 실행 대상.

</details>

```text
타이머 인터럽트 / 자발적 양보
   │
   ▼
1. vruntime 갱신 (실행 시간 × 역가중치 누적)
   │
   ▼
2. 레드-블랙 트리 재조정 (갱신된 vruntime으로 삽입 위치 이동)
   │
   ▼
3. leftmost 노드 선정 (최소 vruntime 프로세스)
   │
   ▼
4. 동적 타임 슬라이스 계산
   └─ max(sched_latency × 가중치 비율, min_granularity)
   │
   ▼
5. 선정 프로세스 CPU 이양 및 실행
```

**동작 원리**

1. **vruntime 갱신**: 실행 시간에 나이스 값 역가중치를 곱하여 현재 프로세스의 **vruntime**을 누적 갱신
2. **트리 재조정**: 갱신된 vruntime으로 레드-블랙 트리 내 위치를 재배치하여 정렬 유지
3. **leftmost 선정**: 트리의 최소 vruntime(leftmost) 노드를 다음 실행 대상으로 결정
4. **타임 슬라이스 계산**: sched_latency와 가중치 비율로 동적 타임 슬라이스를 산출하되 **min_granularity** 하한 보정

#### 한줄 요약

- 실행 후 vruntime을 갱신하고 트리를 재배치하여 최소 vruntime 프로세스를 다음 실행 대상으로 선정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **O(1) 스케줄러**: CFS 이전 리눅스 스케줄러로, 고정 타임 슬라이스와 활성·만료 큐 쌍을 사용하여 O(1) 선정을 달성하지만 공정성 보장이 부족한 방식.

</details>

| 비교 항목 | CFS | O(1) 스케줄러 | MLFQ |
|:---|:---|:---|:---|
| 적용 기준 | 공정 배분 필요 범용 Linux 멀티태스킹 | 고정 우선순위 기반 단순 배치 처리 | I/O·CPU 혼합 워크로드 적응형 분류 |
| 핵심 특징 | **vruntime** 기반 공정 배분·레드-블랙 트리 | 고정 **타임 슬라이스**·활성/만료 큐 쌍 | 실행 이력 기반 동적 큐 강등·승격 |
| 한계 및 위험 | 대규모 멀티코어에서 **cfs_rq** 잠금 경합 증가 | 부하 변동 시 불공정 배분 발생 | 파라미터 튜닝 복잡성 |

#### 한줄 요약

- 공정성은 CFS, 단순 고정 배치는 O(1), 혼합 워크로드 자동 분류는 MLFQ 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **cgroup CPU 쿼터**: 컨테이너·프로세스 그룹의 최대 CPU 사용량을 제한하는 리눅스 cgroup v2 기반 자원 할당 기법.
- **NUMA 인식(NUMA-aware) 스케줄링**: 멀티소켓 시스템에서 프로세스를 자신의 메모리와 같은 NUMA 노드의 코어에 배치하여 원격 메모리 접근 지연을 감소시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 컨테이너 간 CPU 독점으로 **공정 배분** 훼손 | **cgroup CPU 쿼터** 기반 최대 CPU 사용량 제한 | 컨테이너 간 CPU 할당 공정성 확보 |
| 멀티소켓 환경에서 원격 NUMA 메모리 접근 지연 | **NUMA 인식 스케줄링**으로 로컬 노드 코어 배치 | 원격 메모리 접근 지연 감소 |
| 지나치게 짧은 타임 슬라이스로 문맥 전환 과부하 | **min_granularity** 하한값 상향 조정 | 문맥 전환 오버헤드 감소 및 처리량 향상 |

#### 한줄 요약

- 컨테이너 독점은 cgroup 쿼터로, NUMA 지연은 NUMA 인식 배치로, 전환 과부하는 min_granularity 조정으로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CFS 적용 판단 기준**: 공정 CPU 배분과 나이스 값 기반 우선순위 조정이 필요한 범용 Linux 멀티태스킹 환경에서 CFS를 선택하는 기준.

</details>

- 공정 배분이 요구되는 범용 멀티태스킹은 **CFS**, 엄격한 응답 기한은 **실시간(RT) 스케줄러** 선택

#### 한줄 요약

- 공정성·유연한 우선순위 조정이 필요한 범용 환경은 CFS, 마감 기한 엄격 보장은 실시간 스케줄러를 선택
