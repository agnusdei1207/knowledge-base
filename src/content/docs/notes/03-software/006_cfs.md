## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **완전 공정 스케줄러(Completely Fair Scheduler, CFS)**: 가중치로 보정한 CPU 사용량이 가장 적은 태스크를 선택하는 공정 스케줄러이다.
- **가상 실행시간(Virtual Runtime, vruntime)**: 실제 실행시간을 태스크 가중치로 보정한 누적값이다.

</details>

- 정의/개념: 가중치로 보정한 **vruntime**이 가장 작은 태스크에 CPU를 배분하는 공정 스케줄링 정책이다.
- 배경/필요성: 동일 시간 할당만으로는 태스크별 **가중 CPU 몫 반영할 수 없다**.

#### 한줄 요약

- 가중 CPU 사용량이 가장 작은 **최소 vruntime 태스크**를 선택한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **최소 세분도(Minimum Granularity)**: 태스크별 실행 구간이 더 짧아지지 않도록 정한 하한이다.
- **깨움 세분도(Wakeup Granularity)**: 새로 깨어난 태스크가 현재 태스크를 선점할 민감도 기준이다.

</details>

- **가중 가상 실행시간**으로 태스크별 CPU 몫을 추적한다.
- **최소 vruntime 태스크 선택**으로 공정한 실행 기회를 제공한다.
- **최소•깨움 세분도 감소** 시 응답 지연 감소•전환 비용 증가한다.

#### 한줄 요약

- 실행 태스크 증가 시 **실행 구간 단축•최소 세분도 하한**을 적용한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **스케줄링 개체(Scheduling Entity)**: 태스크의 가중치와 가상 실행시간을 보관하는 스케줄링 상태이다.
- **CFS 실행 큐(CFS Run Queue, cfs_rq)**: 레드-블랙 트리로 실행 개체를 vruntime 순서로 관리하는 구성한다.
- **CFS 스케줄러(CFS Scheduler)**: 가중치와 배분 구간으로 최소 개체와 실행 구간을 정하는 구성한다.
- **CPU**: 선택 태스크를 실행하고 실제 CPU 사용시간을 제공하는 구성한다.

</details>

```text
[스케줄링 개체]
        |
[CFS 실행 큐]
        |
[CFS 스케줄러]
        |
      [CPU]
```

선의 의미: 스케줄링 개체와 실행 큐의 선은 가중치•가상 실행시간 등록 관계, 실행 큐와 스케줄러의 선은 최솟값 후보 제공 관계, 스케줄러와 CPU의 선은 선택한 태스크에 실행 자원을 배정하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 스케줄링 개체 | **가중치•vruntime 보관** |
| CFS 실행 큐 | **vruntime 순서 유지** |
| CFS 스케줄러 | **최솟값•실행 구간 산정** |
| CPU | **선택 태스크 실행** |

- **vruntime 증가량**: 실제 실행시간 × 기준 가중치 / 태스크 가중치이다.
- **이상적 실행 몫**: 배분 구간 × 태스크 가중치 / 전체 가중치 합이다.

#### 한줄 요약

- **스케줄링 개체•vruntime 정렬•최솟값 선택** 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **디스패치(Dispatch)**: 선택한 태스크의 실행 문맥을 복원하고 CPU 제어권을 넘기는 동작이다.
- **가중치 역비례 누적**: CPU 몫이 큰 태스크일수록 같은 실행시간에 vruntime을 더 적게 늘리는 계산한다.
- **vruntime 정렬 엔트리**: 태스크의 가상 실행시간과 가중치를 담아 실행 큐의 정렬 기준으로 사용하는 항목이다.

</details>

```text
┌──────────── CFS 배분 반복 ────────────┐
│ 1. 최소 vruntime 개체 선택            │
│          │                             │
│          ▼                             │
│ 2. 가중 실행 구간 산정                │
│          │                             │
│          ▼                             │
│ 3. 태스크 디스패치•실행               │
│          │                             │
│          ▼                             │
│ 4. vruntime 가중 누적                 │
│          │                             │
│          ▼                             │
│ 5. 실행 큐 재삽입                     │
│          └── 최소 vruntime 선택으로 반복
└───────────────────────────────────────┘
```

**동작 원리**

1. **최소 vruntime 개체 선택**: 트리 최솟값을 실행 후보로 결정한다.
2. **가중 실행 구간 산정**: 가중치 비율과 세분도 하한을 반영한다.
3. **태스크 디스패치•실행**: 문맥 복원 후 실제 CPU 시간을 소비한다.
4. **vruntime 가중 누적**: 실제 실행시간을 가중치 역비례로 반영한다.
5. **실행 큐 재삽입**: 갱신값 순서로 개체 위치를 조정한다.

#### 한줄 요약

- **최소 vruntime 선택•가중 누적**의 공정 배분 반복이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **라운드 로빈(Round Robin, RR)**: 준비 큐의 태스크에 같은 시간 할당량을 차례로 배분하는 방식이다.
- **가중 배분**: 태스크별 가중치 비율에 맞춰 서로 다른 CPU 몫을 제공하는 방식이다.

</details>

| 스케줄링 정책 | CFS | 라운드 로빈 |
|:---|:---|:---|
| 적용 기준 | 가중치별 **CPU 몫 배분** | 동일 할당량의 **순환 응답** |
| 핵심 특징 | 최소 vruntime•**가중 배분** | 준비 큐 선두•**동일 할당량** |
| 한계 | 세분도 설정•**계측 비용** | 짧은 할당량의 **전환 증가** |

> 요약: 가중 CPU 몫은 **CFS**, 동일 시간 순환은 **라운드 로빈**을 선택한다.

#### 한줄 요약

- **CFS 가중 몫•RR 동일 할당량**의 선택 기준 차이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **nice 값(Nice Value)**: 태스크의 CPU 배분 가중치를 정하는 값이다.
- **그룹 스케줄링(Group Scheduling)**: 태스크를 그룹으로 묶어 CPU 몫을 계층적으로 배분하는 방식이다.
- **런 큐 지연(Run-Queue Latency)**: 실행 가능해진 태스크가 실제 CPU를 받기까지 기다린 시간이다.
- **꼬리 응답시간(Tail Response Time)**: 응답시간 분포의 상위 백분위에 해당하는 느린 요청 시간이다.
- **문맥 전환(Context Switch)**: 현재 태스크의 실행 상태를 저장하고 다음 태스크의 상태를 복원하는 처리이다.
- **캐시 지역성(Cache Locality)**: 최근 사용한 코드•데이터가 CPU 캐시에 남아 다시 활용되는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 실행 가능 태스크 증가로 실행 구간이 **최소 세분도 수렴** | 태스크를 CPU별 **CFS 실행 큐로 분산** | 과도한 **문맥 전환** 방지 |
| 잘못된 nice•그룹 가중치로 **CPU 몫 왜곡** | **nice•그룹 가중치**와 실사용 몫 재조정 | 목표 **가중 공정성** 유지 |
| 깨움 선점이 잦아 현재 태스크의 **캐시 지역성 손실** | 응답 목표 기반 **깨움 세분도 조정** | **응답시간 단축•처리량 보전** |
| 평균 CPU 몫은 맞지만 짧은 구간에 **지연 편중** | 구간별 **런 큐 지연•꼬리 응답시간** 계측 | 순간 **불공정 구간** 식별 |

#### 한줄 요약

- 웹•배치 작업에 **nice•그룹 가중치**별 CPU 몫 배분이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **nice 가중치**: 태스크별 CPU 몫을 조정하는 CFS 기준이다.
- **깨움 세분도**: 깨어난 태스크의 선점 민감도를 조정하는 CFS 기준이다.

</details>

- CPU 몫은 **nice 가중치**, 꼬리 응답 목표는 **깨움 세분도**로 조정한다.

#### 한줄 요약

- **CPU 몫•꼬리 응답 목표**로 가중치•깨움 세분도를 결정한다.
