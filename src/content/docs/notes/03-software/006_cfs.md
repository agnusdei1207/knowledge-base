## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **완전 공정 스케줄러(Completely Fair Scheduler, CFS)**: 타임 슬라이스를 칼같이 쪼개는 대신, 프로세스들이 CPU를 덜 쓴 순서대로 무조건 먼저 챙겨주는 리눅스 특유의 평등주의 스케줄러이다.
- **가상 실행 시간(Virtual Runtime, vruntime)**: 진짜로 일한 시간에 우선순위(나이스 값) 역가중치를 곱해서, "누가 제일 억울하게 못 뛰었나"를 깐깐하게 계산해 낸 억울함의 지표이다.
- **레드-블랙 트리(Red-Black Tree)**: 실행 가능한 프로세스들을 vruntime(억울함) 순으로 쫙 정렬해 놓고, 제일 불쌍한 놈(맨 왼쪽 노드)을 빛의 속도로 뽑아 쓰기 위해 만든 자가 균형 나무 구조이다.

</details>

- 정의: 프로세스의 실행 시간을 가중치 기반 **vruntime**으로 환산하여, CPU 사용량이 가장 적은 놈부터 챙겨주는 이상적인 멀티태스킹 **CFS(완전 공정 스케줄러)**
- 배경: 휴리스틱하게 대화형과 CPU 집중형을 갈라치던 구식 방식(O(1) 스케줄러)으로는, 부하가 변할 때 공정한 CPU 몫을 계산해 내는 게 아예 불가능했기 때문

#### 한줄 요약

- CPU를 덜 쓴 억울한 놈(vruntime 최소값)부터 멱살 잡고 끌어올려 무조건 먼저 챙겨주는 스케줄러이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스케줄 지연 시간(sched_latency)**: 대기열에 있는 모든 프로세스가 적어도 한 번씩은 CPU 맛을 볼 수 있도록 커널이 보장해 주는 전체 순환 주기이다.
- **최소 보장 시간(min_granularity)**: 아무리 쫓겨날 놈이라도 문맥 전환 오버헤드가 더 크면 곤란하니까, 최소한 이 시간만큼은 일하게 해준다고 못 박은 하한선이다.
- **가중치 변환표(prio_to_weight)**: 우선순위(나이스 값)를 커널이 알아먹을 수 있는 CPU 점유 가중치 수치(15~88761)로 변환해 둔 컨닝 페이퍼이다.

</details>

- 고정된 타임 슬라이스가 없고, 전체 주기(**sched_latency**)를 가중치(**prio_to_weight**)로 쪼개서 동적으로 할당함.
- 자가 균형 이진 탐색인 **레드-블랙 트리**를 돌려서 제일 억울한 맨 왼쪽 노드를 시간 복잡도 $O(1)$로 뽑아냄.
- 프로세스가 수천 개로 늘어나 몫이 쪼그라들 때 오버헤드로 터지는 걸 막으려고 **최소 보장 시간**을 강제 적용함.

#### 한줄 요약

- 동적으로 몫을 계산하고 레드-블랙 트리로 줄을 세우며, 오버헤드를 막기 위해 최소 실행 시간을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스케줄링 개체(sched_entity)**: 프로세스 전체 정보 대신, 스케줄링에 필요한 vruntime과 레드-블랙 트리 포인터만 쏙 빼서 만든 가벼운 관리용 구조체이다.

</details>

```text
[ CFS 완전 공정 스케줄링 십자포화 아키텍처 ]
         [ 스케줄링 개체 ]
  (vruntime 억울함 순으로 정렬)
                │
                ▼
      [ CFS 레드-블랙 트리 ]
                │
     (맨 왼쪽 노드 1빠따 추출)
                ▼
        [ CFS 스케줄러 ]
                │
                ▼
       [ CPU (실행 코어) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **스케줄링 개체** (`sched_entity`) | 각 프로세스가 얼마나 억울한지 보여주는 누적 **vruntime**과 트리에 매달릴 포인터 보관 |
| CFS **레드-블랙 트리** | 맨 왼쪽 포인터(`rb_leftmost`)를 뚫어놔서 제일 억울한 놈을 검색 없이 직결로 찾아내는 트리 |
| CFS 스케줄러 | 놈이 일한 만큼 **vruntime**을 갱신하고, 너무 많이 뛰었으면 멱살 잡고 쫓아내는 심판 |
| CPU 코어 | 선택된 놈을 연산시키면서 틱(Tick)마다 타이머를 울려 스케줄러를 깨우는 심장 |

#### 한줄 요약

- 스케줄링 개체를 레드-블랙 트리에 세우고, 스케줄러가 맨 왼쪽의 제일 억울한 놈을 뽑아 CPU에 꽂는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가상 마감시각(Virtual Deadline / EEVDF)**: 최신 리눅스 커널에서 "CFS 넌 다 좋은데 반응이 느려!" 하고 꼬리 응답 시간을 줄이려고 억지로 박아 넣은 납기일 스펙이다.

</details>

```text
[ CFS vruntime 가중 누적 반복 흐름 ]
┌────────── CFS 배분 반복 ──────────┐
│ 1. 최소 vruntime 놈 멱살 잡아 뽑음│
│            │                      │
│            ▼                      │
│ 2. 이번에 뛸 몫(가중 실행 구간) 계산│
│            │                      │
│            ▼                      │
│ 3. 디스패치 후 냅다 실행          │
│            │                      │
│            ▼                      │
│ 4. 타이머 틱마다 vruntime 누적    │
│            │                      │
│            ▼                      │
│ 5. 억울함 풀렸으면 큐에 다시 꽂음 │
│            └── 1번으로 반복 ──────┘
└───────────────────────────────────┘
```

### 동작 원리

1. 최소 vruntime 놈 뽑음: 레드-블랙 트리의 맨 왼쪽 노드에 걸려 있는 제일 억울한 놈을 래칭함.
2. 동적 몫 계산: 가중치 변환표(**prio_to_weight**)를 뒤져서 이번 턴에 뛸 수 있는 시간을 계산함.
3. 디스패치 및 실행: 사용자 모드로 놈을 깨워서 CPU에 던져넣고 진짜 연산을 시킴.
4. vruntime 누적: 타이머 틱이 울릴 때마다 실제 일한 시간에 역가중치(Nice가 높으면 더 빨리 증가)를 곱해 **vruntime**을 올림.
5. 트리 재삽입: 억울함이 풀려서 남들보다 vruntime이 커지면 쫓아내고 다시 레드-블랙 트리에 정렬시킴.

#### 한줄 요약

- 억울한 놈(vruntime 최소값)을 뽑아 몫을 주고 돌리다가, vruntime이 오르면 다시 트리에 처박는다.

## Ⅴ. 종류 및 비교

| 비교 항목 | **CFS** (Completely Fair Scheduler) | **EEVDF** (차세대 리눅스 6.6+) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 서버 수천 대가 골고루 CPU 몫을 나눠 먹으며 튼튼하게 돌아야 할 때 | 게임이나 리얼타임 연산처럼 클릭하면 0.1초 안에 무조건 반응해야 할 때 |
| 핵심 공정성 기준표 | 무조건 **vruntime**(억울함의 지표)이 제일 낮은 놈부터 무식하게 챙겨줌 | vruntime도 보지만 **가상 마감시각**이 촉박한 놈한테 새치기를 허용함 |
| 타임 슬라이스 설계 | 전체 주기(**sched_latency**)를 가중치로 쪼개서 동적으로 할당량을 계산함 | 동적 가변은 똑같지만, 납기 지연(Lag)을 방어하려고 스케줄러가 미세 개입함 |

#### 한줄 요약

- CFS는 평등이 최고라 응답 속도를 챙겨주지 않고, EEVDF는 평등하게 주면서도 마감일 급한 놈을 봐준다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오토그룹 / 씨그룹(Autogroup / Cgroups)**: 스레드를 100개 찍어내는 꼼수 프로세스가 CPU를 싹쓸이하는 걸 막으려고, 프로세스 단위가 아니라 사용자 그룹 단위로 몫을 강제 배분하는 족쇄이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프로세스가 수천 개로 폭증해서 지분이 개미눈물만큼 쪼개져 문맥 전환 지연으로 뻗어버림 | 시스템 파라미터로 **최소 보장 시간(min_granularity)** 하한선을 튜닝해서 멱살 잡음 | 쓸데없이 잦은 문맥 전환 낭비를 틀어막고 최소한의 일할 시간을 확보 |
| 대화형 서비스가 무거운 백그라운드 연산에 밀려서 반응이 굼벵이처럼 늘어짐 | 대화형 프로세스의 **나이스(Nice)** 값을 확 낮춰서 억울함(vruntime)이 천천히 차게 꼼수 씀 | 우선순위 가중치를 먹고 최우선으로 선점 당해 대화형 응답성 떡상 |
| 한 놈이 스레드를 미친 듯이 찍어내서 전체 CPU 몫을 치사하게 독식해 버림 | **씨그룹(Cgroups v2)**에 가둬놓고 그룹 단위로 CPU 쿼터 몫을 강제로 배분함 | 꼼수 부리는 멀티스레드 사용자의 독점을 막고 테넌트 간 공정성 회복 |

#### 한줄 요약

- 오버헤드는 최소 보장 시간으로 막고, 중요한 프로세스는 나이스 값을 낮추며, 꼼수는 그룹으로 묶어 패라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CFS 스케줄러 튜닝 기준(CFS Tuning Criteria)**: 프로세스 개수, 나이스 가중치, 시스템 딜레이 허용치를 따져서 완전 공정 스케줄러가 멍청해지지 않게 멱살 잡는 세팅 잣대이다.

</details>

- **CFS 스케줄러 튜닝 기준** 원칙에 따라, 몫 배분이 생명인 범용 서버는 **CFS** 튜닝으로 승부를 보고, 반응성이 1순위면 최신 **EEVDF 정책** 채택 기조 확립함

#### 한줄 요약

- 몫 배분은 CFS의 튜닝으로 잡고, 지연 시간에 민감하면 마감을 챙기는 최신 EEVDF 정책을 도입하라.
