## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CFS(Completely Fair Scheduler)**: vruntime을 기준으로 CPU 시간을 가중 배분하는 리눅스 스케줄러.
- **vruntime(가상 실행 시간)**: 프로세스의 실제 물리 실행 시간에 nice 우선순위 역가중치를 곱하여 누적한 공정 배분 척도.

</details>

- 정의/개념: **vruntime**(가상 실행 시간)을 레드-블랙 트리로 관리하여 최소 점유 프로세스를 우선 디스패치하는 리눅스 표준 **CFS** 스케줄러
- 배경/필요성: O(1) 스케줄러는 슬립 시간 휴리스틱으로 대화형을 추정해 오판 시 CPU 독점·기아를 낳았으므로, 실행 시간을 가중 누적한 vruntime 하나로 순서를 정해 휴리스틱 계층을 제거하는 공정 스케줄러가 필요

#### 한줄 요약
- 최소 vruntime 프로세스를 선정해 가중치 비율로 CPU 시간을 배분한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **sched_latency**: 준비 큐의 모든 실행 가능 프로세스가 최소 1회씩 CPU를 할당받는 전체 목표 순환 주기.
- **min_granularity**: 프로세스 수가 급증할 때 문맥 전환 지연이 실제 연산 시간을 압도하지 않도록 보장하는 최소 실행 시간 하한.
- **레드-블랙 트리(Red-Black Tree)**: 삽입·삭제 시 색 규칙으로 높이를 log n에 묶어 두는 자가 균형 이진 탐색 트리로, CFS가 vruntime 순 정렬과 최소값 탐색에 사용.

</details>

- 고정 타임 슬라이스 대신 **sched_latency**를 프로세스 가중치(nice) 비율로 나눈 동적 타임 퀀텀 할당
- **레드-블랙 트리**의 최좌측 노드를 캐싱해 선정 비용 절감
- 프로세스 폭증 시 문맥 전환 오버헤드를 막기 위한 **min_granularity** 최소 실행 시간 보장

#### 한줄 요약
- 완전 공정성은 nice 가중치 계산과 트리 정렬 비용을 매 전환마다 지불하고 얻은 것이며, 그 대신 대화형 판정을 위한 휴리스틱을 통째로 버릴 수 있게 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **sched_entity**: 프로세스 또는 cgroup의 vruntime, 가중치, 트리 노드 포인터를 담은 CFS 스케줄링 단위 구조체.
- **cfs_rq**: CPU 코어별로 실행 대기 중인 sched_entity들을 vruntime 오름차순으로 관리하는 CFS 전용 런 큐.

</details>

```text
[리눅스 CFS 스케줄러 아키텍처]
|-- cfs_rq (CPU 코어별 CFS 런 큐)
|   `-- 레드-블랙 트리 (vruntime 오름차순 정렬)
|       |-- rb_leftmost 캐시
|       |-- sched_entity B (중간 vruntime)
|       `-- sched_entity C (vruntime 최대)
`-- 커널 스케줄러 엔진
    |-- 동적 타임 슬라이스 연산기 (sched_latency * weight / total_weight)
    |-- min_granularity 하한 보호기
    `-- vruntime 갱신 모듈 (실제 실행시간 * 1024 / weight)
```

선의 의미: 계층 및 레드-블랙 트리 정렬 구조

| 구성요소 | 책임 |
|:---|:---|
| cfs_rq | 코어별 **sched_entity**를 **vruntime** 순으로 보관 |
| sched_entity | **vruntime**·nice 가중치·통계 보관 |
| 레드-블랙 트리 | vruntime 기준 $O(\log n)$ 삽입·삭제 |
| rb_leftmost | 최소 vruntime 노드 포인터 캐싱 |

#### 한줄 요약
- 레드-블랙 트리가 최소 vruntime 태스크 선택을 로그 시간에 고정해 실행 대상 판단에서 휴리스틱을 걷어내며, 가중치는 vruntime의 증가 속도를 바꾸는 방식으로만 개입한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **leftmost 노드**: 레드-블랙 트리에서 vruntime이 가장 작은 맨 왼쪽 노드로, 다음 실행 대상.

</details>

```text
타이머 인터럽트 발생 또는 프로세스 자발 반납
        │
   현재 실행 프로세스의 vruntime 갱신 (실제 실행시간 * 1024 / weight)
        │
   갱신된 프로세스를 레드-블랙 트리에 재삽입 (정렬 위치 재조정)
        │
   트리의 맨 왼쪽 leftmost 노드(최소 vruntime)를 차기 실행 대상으로 선정
        │
   동적 타임 슬라이스 계산 : max(sched_latency * 가중치 비율, min_granularity)
        │
   선정된 프로세스로 CPU 문맥 전환 및 실행 재개
```

분기 결과: 매 전환마다 vruntime 갱신·트리 재삽입 비용이 들지만 차기 대상 선정은 캐시된 **leftmost 노드** 조회 한 번으로 끝나며, 타임 슬라이스가 min_granularity 하한에 걸리면 공정 배분보다 전환 비용 억제를 우선한다.

#### 한줄 요약
- vruntime 갱신과 트리 재삽입이 매 전환마다 반복되는 비용이지만, 그 대가로 실행 대상 선정이 leftmost 노드 조회 한 번으로 끝나 판단에 휴리스틱이 끼어들 여지가 사라진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **O(1) 스케줄러**: CFS 이전의 리눅스 스케줄러로, 140개 우선순위별 활성/만료 비트맵 큐를 사용하던 방식.

</details>

| 스케줄러 알고리즘 | CFS (완전 공정 스케줄러) | O(1) 스케줄러 | MLFQ (다단계 피드백 큐) |
|:---|:---|:---|:---|
| 공정성 배분 척도 | **vruntime (가상 실행 시간)** | **O(1) 스케줄러**의 활성/만료 큐 고정 타임 슬라이스 | 우선순위 계층별 퀀텀 |
| 핵심 자료구조 | **레드-블랙 트리** ($O(\log n)$) | 우선순위 비트맵 큐 2개 ($O(1)$) | 다단계 우선순위 연결 리스트 |
| 대화형 판별 방식 | 대기 시 vruntime 지연 자연 보상 | 슬립 시간 기반 휴리스틱 계산 | 퀀텀 소진 여부로 강등/유지 |
| 한계점 | 프로세스 수 증가 시 트리 오버헤드 | 부하 변동 시 휴리스틱 오판단 | 튜닝 복잡도 및 기아 방지 필요 |

#### 한줄 요약
- vruntime으로 CPU 시간을 가중 배분하고 대기 작업을 보상한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **cgroup CPU 쿼터**: 컨테이너 가상화(Docker/K8s)에서 특정 cgroup 그룹의 최대 CPU 사용량을 마이크로초 단위로 강제 제한하는 기법.
- **NUMA 인식 스케줄링(NUMA-aware Scheduling)**: 멀티소켓 서버에서 프로세스와 메모리를 동일한 NUMA 노드에 배치하여 원격 접근 지연을 줄이는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 멀티테넌트 컨테이너의 CPU 독점 | **cgroup CPU 쿼터**·가중치 설정 | 컨테이너별 CPU 상한과 비율 통제 |
| 멀티소켓 환경에서 원격 NUMA 메모리 접근 지연 | **NUMA 인식 스케줄링**(AutoNUMA) 활성화 | 메모리 지역성 확보 및 소켓 간 인터커넥트 병목 완화 |
| 고빈도 짧은 작업으로 인한 문맥 전환 오버헤드 | **min_granularity** 상향 튜닝 | 최소 실행 시간 보장을 통한 CPU 유효 처리율 증대 |
| 실시간 오디오·영상의 마감시간 초과 | SCHED_FIFO·SCHED_RR 우선순위 격리 | CFS와 분리해 지연 변동 감소 |

#### 한줄 요약
- CFS의 완전 공정성은 개별 작업의 지연을 보장하지 않으므로, 지연에 민감한 작업은 실시간 정책으로 빼내고 나머지는 cgroup 가중치로 몫만 나누어 공정성과 결정성을 서로 다른 계층에서 얻는다.

## Ⅶ. 결론

- 리눅스 커널(v2.6.23~v6.5)의 핵심 범용 공정 스케줄러(최근 커널 v6.6+에서는 지연 최적화 EEVDF로 진화)로 입증되었으며, 실무 클라우드/컨테이너 환경에서는 K8s/Docker CPU 자원 제한을 위한 `cgroup v2 cpu.weight/cpu.max`, 스레드 폭증 시 문맥 전환 지연을 막는 `sched_min_granularity_ns` 튜닝 및 소켓 간 메모리 지역성을 보장하는 AutoNUMA를 결합하여 대규모 워크로드를 안정 운영

#### 한줄 요약
- 범용 부하는 CFS, 마감시간 작업은 실시간 정책으로 분리한다.
