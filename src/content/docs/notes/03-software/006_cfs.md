## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CFS(Completely Fair Scheduler)**: 가상 런타임(vruntime)을 기반으로 모든 실행 가능 프로세스에게 공평한 CPU 점유 시간을 보장하는 리눅스 기본 스케줄러.
- **vruntime(가상 실행 시간)**: 프로세스의 실제 물리 실행 시간에 nice 우선순위 역가중치를 곱하여 누적한 공정 배분 척도.

</details>

- 정의/개념: **가상 실행 시간(vruntime)** 을 레드-블랙 트리로 관리하여 최소 점유 프로세스를 우선 디스패치하는 리눅스 표준 **CFS** 스케줄러
- 배경/필요성: 기존 $O(1)$ 스케줄러의 휴리스틱 판정 한계로 인해 **부하 변동 시 CPU 자원 불공정 배분 및 굶주림 문제 해결 불가**

#### 한줄 요약
- vruntime이 가장 작은 프로세스를 레드-블랙 트리에서 $O(\log n)$으로 선정하여 완전한 공정성을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **sched_latency**: 준비 큐의 모든 실행 가능 프로세스가 최소 1회씩 CPU를 할당받는 전체 목표 순환 주기.
- **min_granularity**: 프로세스 수가 급증할 때 문맥 전환 지연이 실제 연산 시간을 압도하지 않도록 보장하는 최소 실행 시간 하한.

</details>

- 고정 타임 슬라이스 대신 **sched_latency**를 프로세스 가중치(nice) 비율로 나눈 동적 타임 퀀텀 할당
- **레드-블랙 트리(Red-Black Tree)** 의 최좌측 노드(leftmost)를 $O(1)$ 캐싱하여 초고속 디스패치
- 프로세스 폭증 시 문맥 전환 오버헤드를 막기 위한 **min_granularity** 최소 실행 시간 보장

#### 한줄 요약
- nice 가중치 기반의 동적 타임 슬라이스 분배와 레드-블랙 트리 기반 $O(\log n)$ 정렬로 공정성을 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **sched_entity**: 프로세스 또는 cgroup의 vruntime, 가중치, 트리 노드 포인터를 담은 CFS 스케줄링 단위 구조체.
- **cfs_rq**: CPU 코어별로 실행 대기 중인 sched_entity들을 vruntime 오름차순으로 관리하는 CFS 전용 런 큐.

</details>

```text
[리눅스 CFS 스케줄러 아키텍처]
|-- cfs_rq (CPU 코어별 CFS 런 큐)
|   `-- 레드-블랙 트리 (vruntime 오름차순 정렬)
|       |-- rb_leftmost 캐시 -> sched_entity A (vruntime 최소 -> 즉시 디스패치)
|       |-- sched_entity B (중간 vruntime)
|       `-- sched_entity C (vruntime 최대)
`-- 커널 스케줄러 엔진
    |-- 동적 타임 슬라이스 연산기 (sched_latency * weight / total_weight)
    |-- min_granularity 하한 보호기
    `-- vruntime 갱신 모듈 (실제 실행시간 * 1024 / weight)
```

선의 의미: 계층 및 레드-블랙 트리 정렬 구조

| 구성요소 | 책임 |
|:---|:---|
| **cfs_rq** | 코어별로 실행 가능한 프로세스를 **vruntime** 순으로 보관하는 런 큐 |
| **sched_entity** | 프로세스별 **vruntime**, nice 가중치, 통계 데이터를 보관하는 스케줄링 엔티티 |
| **레드-블랙 트리** | vruntime 오름차순으로 노드를 자가 균형 정렬하여 $O(\log n)$ 삽입/삭제 수행 |
| **rb_leftmost** | 트리의 맨 왼쪽 최소 vruntime 노드를 포인터로 직접 캐싱하여 $O(1)$ 즉시 디스패치 |

#### 한줄 요약
- cfs_rq 런 큐, 레드-블랙 트리, sched_entity 구조체가 결합되어 최소 vruntime을 추적한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **leftmost 노드**: 레드-블랙 트리에서 vruntime이 가장 작은 맨 왼쪽 노드로, 다음 실행 대상.

</details>

```text
타이머 인터럽트 발생 또는 프로세스 자발 반납
        │
   현재 실행 프로세스의 vruntime 갱신 (실제 실행시간 * 1024 / weight)
        │
   갱신된 프로세스를 레드-블랙 트리에 재삽입 (정렬 위치 재조정)
        │
   트리의 맨 왼쪽 leftmost 노드(최소 vruntime)를 차기 실행 대상으로 선정
        │
   동적 타임 슬라이스 계산 : max(sched_latency * 가중치 비율, min_granularity)
        │
   선정된 프로세스로 CPU 문맥 전환 및 실행 재개
```

#### 한줄 요약
- vruntime 갱신 → 레드-블랙 트리 재삽입 → leftmost 노드 선정 → 타임 슬라이스 부여 후 실행 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **O(1) 스케줄러**: CFS 이전의 리눅스 스케줄러로, 140개 우선순위별 활성/만료 비트맵 큐를 사용하던 방식.

</details>

| 스케줄러 알고리즘 | CFS (완전 공정 스케줄러) | O(1) 스케줄러 | MLFQ (다단계 피드백 큐) |
|:---|:---|:---|:---|
| 공정성 배분 척도 | **vruntime (가상 실행 시간)** | 활성/만료 큐 고정 타임 슬라이스 | 우선순위 계층별 퀀텀 |
| 핵심 자료구조 | **레드-블랙 트리 ($O(\log n)$)** | 우선순위 비트맵 큐 2개 ($O(1)$) | 다단계 우선순위 연결 리스트 |
| 대화형 판별 방식 | 대기 시 vruntime 지연 자연 보상 | 슬립 시간 기반 휴리스틱 계산 | 퀀텀 소진 여부로 강등/유지 |
| 한계점 | 프로세스 수 증가 시 트리 오버헤드 | 부하 변동 시 휴리스틱 오판단 | 튜닝 복잡도 및 기아 방지 필요 |

#### 한줄 요약
- 복잡한 휴리스틱 없이 수학적 vruntime으로 완벽한 공정성과 대화형 응답을 동시에 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **cgroup CPU 쿼터**: 컨테이너 가상화(Docker/K8s)에서 특정 cgroup 그룹의 최대 CPU 사용량을 마이크로초 단위로 강제 제한하는 기법.
- **NUMA 인식 스케줄링(NUMA-aware Scheduling)**: 멀티소켓 서버에서 프로세스와 메모리를 동일한 NUMA 노드에 배치하여 원격 접근 지연을 줄이는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 멀티테넌트 컨테이너 간 CPU 독점 및 굶주림 | **cgroup v2 CPU 쿼터 및 CFS Shares** 설정 | 컨테이너별 CPU 상한 통제 및 공정 배분 보장 |
| 멀티소켓 환경에서 원격 NUMA 메모리 접근 지연 | **AutoNUMA 및 NUMA 인식 스케줄링** 활성화 | 메모리 지역성 확보 및 소켓 간 인터커넥트 병목 완화 |
| 고빈도 짧은 작업으로 인한 문맥 전환 오버헤드 | **`sysctl kernel.sched_min_granularity_ns`** 상향 튜닝 | 최소 실행 시간 보장을 통한 CPU 유효 처리율 증대 |
| 실시간 오디오/영상 처리 시 마감시간 초과 | `SCHED_FIFO` / `SCHED_RR` 실시간 우선순위 격리 배정 | CFS 공정성 제어를 우회하여 무지연 실시간 처리 달성 |

#### 한줄 요약
- cgroup 쿼터, NUMA 인식 스케줄링, min_granularity 튜닝, 실시간 스케줄링 분리로 성능을 최적화한다.

## Ⅶ. 결론

- 범용 클라우드 및 컨테이너 인프라는 **CFS 스케줄러**를 기반으로 구축하고, **cgroup 쿼터 및 NUMA 친화성**을 결합하여 멀티테넌트 공정성과 고성능 동시 확립

#### 한줄 요약
- CFS는 가상 런타임과 레드-블랙 트리를 통해 휴리스틱 없이 공정성과 효율성을 완벽히 구현한 현대 운영체제의 핵심 스케줄러다.
