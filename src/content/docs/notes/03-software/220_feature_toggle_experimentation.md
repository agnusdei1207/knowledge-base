## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **기능 노출 시점•대상**: 피처 토글은 코드 배포와 기능 노출 시점•대상을 분리해 요청별 실행 경로를 제어한다.
- **피처 토글(Feature Toggle)**: 코드 배포와 기능 활성화를 분리하고 사용자•환경•비율 조건에 따라 실행 경로를 바꾸는 릴리스 제어 기법이다.

</details>

- 정의/개념: **기능 토글 실험** 은 코드 배포와 기능 노출을 분리하고 사용자•환경•비율 조건에 따라 기능을 켜고 꺼서 단계 공개와 실험을 수행하는 릴리스 제어 기법
- 배경/필요성: 배포•노출 결합으로 **부분 실험•즉시 차단 불가**

#### 한줄 요약
- 새 코드는 미리 배포해 두고 스위치로 일부 사용자에게만 열어 이상 시 배포 롤백 없이 즉시 닫는다

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **대조군•변종군 배정**: 안정 키와 무작위 해시를 사용해 같은 사용자를 실험 기간 동안 일관된 대조군•변종군에 배정한다.
- **안정 키(Stable Key)**: 같은 사용자가 실험 기간 내내 동일한 집단에 배정되도록 사용하는 변하지 않는 식별자이다.
- **노출 로그(Exposure Log)**: 어떤 사용자에게 어느 시점에 어떤 변종이 실제 표시됐는지 기록한 데이터이다.

</details>

- 배포와 **기능 활성화 시점 분리**
- 무작위 해시의 **대조군•변종군 배정**
- 노출 로그의 **기능 효과 검증**

#### 한줄 요약
- 같은 사용자에게 같은 변종을 보여 주고 실제 노출 기록과 성과를 연결해야 기능 차이만 비교할 수 있다

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **평가 런타임(Evaluation Runtime)**: 요청 시 플래그 정책을 계산해 실행할 기능 경로를 반환한다.
- **소프트웨어 개발 키트(Software Development Kit, SDK)**: 애플리케이션이 플래그를 평가하고 노출을 기록하도록 제공되는 라이브러리와 도구 모음이다.
- **플래그 제어부(Flag Control Plane)**: 토글의 소유자•규칙•버전•만료일을 관리하고 평가 런타임에 배포하는 구성요소이다.

</details>


| 구성요소 | 책임 |
|:---|:---|
| 플래그 제어부 | 소유자•규칙•**버전•만료 관리** |
| 할당•노출 정책 | 속성•안정 키 기반 **실험군 일관 배정** |
| 평가 런타임•SDK | 규칙 계산•**기능 분기** |
| 애플리케이션 | 기존•후보 **실행•노출 기록** |
| 실험 분석 | 성과•가드레일 **확대•중단 판정** |


#### 한줄 요약
- 제어부가 토글 규칙을 배포하면 런타임이 사용자 집단을 정하고 앱과 분석기가 노출•성과를 연결한다

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **5. 확대•중단 판정**: 사전에 정한 효과•가드레일 지표와 관측 기간, 통계적 유의성을 기준으로 기능 노출을 확대하거나 중단한다.
- **1. 가설•지표 정의**: 기대 효과와 오류율 등 안전 지표를 실험 전에 고정하는 단계이다.
- **2. 플래그 정책 등록**: 소유자•대상•노출 비율•만료일을 불변 버전으로 기록하는 단계이다.
- **3. 정책 버전 활성화**: 승인된 규칙을 평가 런타임의 요청 판정에 적용하는 단계이다.
- **4. 노출•성과 기록**: 사용자 배정과 실제 노출 및 업무 결과를 같은 식별자로 연결하는 단계이다.

</details>

```mermaid
sequenceDiagram
    participant P as 제품팀
    participant R as 제어부•평가 런타임
    participant A as 애플리케이션
    participant X as 실험 분석
    P->>R: 1. 가설•지표 정의
    P->>R: 2. 플래그 정책 등록
    R->>R: 3. 정책 버전 활성화
    A->>R: 기능 평가 요청
    R-->>A: 변종 결정
    A->>X: 4. 노출•성과 기록
    X->>P: 5. 확대•중단 판정
```

**동작 원리**

1. **가설•지표 정의**: 기대 효과와 가드레일 지표 설정
2. **플래그 정책 등록**: 소유자•대상•비율•만료일 지정
3. **정책 버전 활성화**: 평가 런타임이 불변 규칙을 요청 판정에 사용
4. **노출•성과 기록**: 사용자 배정과 업무 결과 결속
5. **확대•중단 판정**: 효과•오류율•통계적 유의성을 근거로 **노출 범위 결정**


#### 한줄 요약
- 일부 사용자에게 새 기능을 보여 준 기록과 성과를 묶어 확대•중단을 정하고 끝난 스위치 코드를 제거한다

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **실험 토글**: 실험 토글은 무작위 사용자군에 서로 다른 변종을 노출하고 노출 로그와 업무 성과를 연결해 효과를 비교한다.
- **릴리즈 토글(Release Toggle)**: 배포한 기능을 소수 대상부터 점진적으로 활성화하는 토글이다.
- **운영 토글(Operational Toggle)**: 장애 기능을 배포 롤백 없이 즉시 차단하거나 대체 경로로 바꾸는 토글이다.

</details>

| 피처 토글 유형 | 릴리즈 토글 | 실험 토글 | 운영 토글 |
|:---|:---|:---|:---|
| 적용 기준 | 배포 후 **점진 노출** | **가설•지표 비교** 필요 | 긴급 **기능 차단** 필요 |
| 핵심 특징 | 기능의 **단계적 개방** | 집단별 **효과 측정** | 장애 기능 **즉시 차단** |
| 한계 | 제거 지연•**분기 누적** | 표본 편향•**오노출** | 상시 의존•**복구 누락** |

> 요약: 노출 목적별 **토글 유형**, 종료 시 **분기 제거 조건** 지정

#### 한줄 요약
- 점진 공개는 릴리즈, 효과 비교는 실험, 긴급 차단은 운영 토글로 나누고 종료 뒤 분기를 지운다

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **토글 잔존**: 토글 잔존은 실험이나 출시가 끝난 분기 코드가 제거되지 않아 조건 복잡도와 시험 조합을 계속 늘리는 문제다.
- **일관 해시(Consistent Hashing)**: 안정 키의 해시값으로 사용자를 동일 실험군에 반복 배정하는 방식이다.
- **통계적 유의성(Statistical Significance)**: 관측한 집단 차이가 우연만으로 발생했다고 보기 어려운 정도이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사용 종료 뒤 **토글 잔존** | 소유자•만료일•**자동 정리** | 조건 복잡성 **감소** |
| 사용자별 **할당 불일치** | 안정 키•**일관 해시 적용** | 실험 오염 **방지** |
| 반복 확인의 **유의성 왜곡** | 사전 지표•기간•**중단 규칙** | 통계 신뢰성 **확보** |
| 실험 자료의 **동의 누락** | 최소 수집•**목적 동의 적용** | 프라이버시 **보호** |

#### 한줄 요약
- 결제 오류가 임계를 넘으면 배포 없이 기능을 끔



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **운영 토글 적용**: 장애 기능을 배포 롤백 없이 즉시 차단
- **토글 수명주기(Toggle Lifecycle)**: 토글 생성•활성화•판정•확대 또는 중단•분기 코드 제거까지 관리하는 절차이다.

</details>

- 점진 노출•효과 비교는 **릴리즈•실험 토글**, 장애 차단은 **운영 토글**

#### 한줄 요약
- 토글 목적과 만료일을 먼저 정하고 노출 결과를 판정한 뒤 남은 분기 코드를 제거한다
