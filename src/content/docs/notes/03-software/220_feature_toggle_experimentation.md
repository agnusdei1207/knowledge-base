## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Feature Toggle (피처 플래그)**: 코드 배포(Deployment)와 기능 공개(Release)를 분리하여 재배포 없이 런타임에 기능을 동적으로 켜고 끄는 기술.
- **Deterministic Hashing (결정적 해싱)**: 사용자 ID와 토글 키를 해싱하여 동일 사용자가 항상 일관된 A/B 실험군에 배정되도록 보장하는 기법.

</details>

- 정의/개념: 소스코드 배포와 기능 활성화 시점을 분리하여 **사용자별·비율별로 동적 기능 분기 및 즉시 롤백을 제어하는 릴리스 기술**
- 배경/필요성: 코드 배포와 기능 노출의 강결합으로 인한 **장애 발생 시 재배포 롤백 지연 위험 및 대규모 사용자 대상 점진 릴리즈와 통계적 A/B 실험 통제 불가 한계**

#### 한줄 요약
- 소스코드 재배포 없이 인메모리 플래그 평가와 킬 스위치를 통해 안전한 카나리 출시와 A/B 실험을 구현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Kill Switch**: 신기능 오류율 급증 시 0.1초 만에 플래그를 OFF로 전환하여 서비스를 즉각 방어하는 긴급 차단 기능.
- **Trunk-Based Development**: 장수 브랜치 없이 메인 트렁크에 매일 머지하며, 미완성 기능은 토글로 숨기는 지속적 통합 개발 방식.

</details>

- 코드 배포(Deploy)와 기능 개방(Release)을 시공간적으로 분리하는 **배포와 출시의 디커플링**
- 사용자 속성(지역, 버전) 및 비율(Canary 10%)에 따라 동적으로 분기하는 **정밀 타깃팅 제어**
- 프로덕션 장애 발생 시 재배포 없이 0.1초 만에 기능을 차단하는 **긴급 킬 스위치(Kill Switch)**

#### 한줄 요약
- 배포와 출시 분리, 정밀 타깃팅, 긴급 킬 스위치를 통해 릴리스 리스크를 극소화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **피처 토글 4대 아키텍처**: Flag Control Plane(중앙 룰 관리), Local Evaluation SDK(인메모리 해시 평가), Application(조건부 분기), Experiment Analytics(A/B 통계 검증).

</details>

```text
[피처 토글 플랫폼]
|-- 플래그 제어 평면
|-- 로컬 평가 SDK
|-- 애플리케이션
|-- 실험 분석기
`-- 가드레일 모니터
```

선의 의미: 계층 및 제어 평면의 플래그 룰이 SDK에 실시간 캐시되어 앱이 로컬에서 분기 실행하고 노출 로그를 분석 플랫폼으로 전송하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 플래그 제어 평면 | 규칙·비율·소유자·만료일 관리 |
| 로컬 평가 SDK | 결정적 해시로 분기 결과 계산 |
| 애플리케이션 | 후보 로직 실행과 노출 기록 |
| 실험 분석기 | 전환 지표와 통계적 유의성 검증 |
| 가드레일 모니터 | 임계치 이탈 시 킬 스위치 작동 |

#### 한줄 요약
- 제어 평면이 규칙을 갖고 SDK가 로컬에서 평가하므로, 노출 정책은 중앙에서 바뀌면서도 판정 비용은 각 인스턴스 메모리 안에서 끝난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **피처 토글 5단계**: 가설 및 지표 수립 $\to$ 10% 카나리 룰 등록 $\to$ SDK 로컬 해시 평가 $\to$ 실시간 통계 검증 $\to$ 100% 릴리즈 및 토글 코드 정리.

</details>

```text
1. 가설 정의
      |
2. 규칙 등록
      |
3. 대상 평가
      |
   [가드레일 충족?]
    /       \
  예        아니오
  |           |
4. 점진 확대  킬 스위치
  |
5. 토글 제거
```

- 1. 가설 정의: 성공 지표와 가드레일 지표 설정
- 2. 규칙 등록: 대상·비율·만료일 지정
- 3. 대상 평가: 결정적 해시로 실험군 배정
- 4. 점진 확대: 유의성과 안전 기준 충족 시 확대
- 5. 토글 제거: 출시 완료 분기와 설정 삭제

#### 한줄 요약
- 토글은 켜는 순간이 아니라 지우는 순간에 완결되며, 정리 단계를 건너뛰면 얻은 배포 유연성이 분기 코드의 유지보수 비용으로 되돌아온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마틴 파울러의 4대 피처 토글**: Release Toggle(카나리 릴리즈), Experiment Toggle(A/B 테스트), Operational Toggle(비상 킬 스위치), Permission Toggle(권한 제어).

</details>

| 비교 항목 | 릴리스 토글 (Release Toggle) | 실험 토글 (Experiment Toggle) | 운영 토글 (Operational Toggle) |
|:---|:---|:---|:---|
| 핵심 적용 목적 | 트렁크 기반 개발 시 미완성 기능 은닉 | A/B 테스트 기반 비즈니스 가설 통계 검증 | 시스템 과부하 시 비핵심 기능 즉각 차단 |
| 토글 수명주기 | 단기 (수일 ~ 수주 내 출시 후 삭제) | 중기 (통계적 유의성 확보 시까지 유지) | 장기/영구 (상시 유지되는 시스템 킬 스위치)|
| 주요 동작 형태 | 카나리 0% $\to$ 100% 점진적 비율 롤아웃 | 다중 변종(Control vs Variant) 50:50 분기 | 정상 ON 상태 유지 $\to$ 비상 시 즉시 OFF |
| 방치 시 위험도 | 코드 복잡도 증가 및 토글 부채(Debt) 누적 | 사용자 편향 및 동시 실험 간 간섭 왜곡 | 평상시 미사용으로 정작 비상 시 미작동 위험 |

#### 한줄 요약
- 점진 배포는 릴리스 토글, 가설 검증은 실험 토글, 비상 장애 차단은 운영 토글을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Toggle Debt (토글 부채)**: 출시가 끝났음에도 `if-else` 분기 코드를 삭제하지 않아 코드 복잡도가 $2^N$으로 폭증하고 테스트가 불가능해지는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사용 완료된 플래그가 코드에 방치되어 유지보수성 파괴 (**토글 부채**)| 플래그 등록 시 `만료일(TTL: 최대 30일)` 지정 및 자동 정리 티켓 발행 | 죽은 분기 코드 100% 근절 |
| 토글 평가를 위해 매번 원격 API를 호출하여 애플리케이션 응답 지연 | SDK 내 `인메모리 룰 캐싱 및 SSE 기반 실시간 동기화` 아키텍처 적용 | 토글 평가 오버헤드 1ms 미만 달성 |
| 여러 A/B 테스트가 동시에 진행되면서 실험군 간섭으로 데이터 오염 | 사용자 해시 공간을 분리하는 `직교 레이어(Orthogonal Layering)` 구성 | 실험 간 간섭 왜곡 0건 달성 |
| 플래그 제어 평면 서버 장애 시 전체 애플리케이션 다운 위험 | 로컬 인메모리 기본값(Fallback Value) 보존 및 자율 평가 유지 | 제어 평면 장애 격리 달성 |

#### 한줄 요약
- 네 대책은 런타임 분기를 얻은 대가인 토글 부채·평가 지연·실험 간섭을 만료 규칙과 로컬 평가로 되사는 선택이다.

## Ⅶ. 결론

- 트렁크 기반 개발(Trunk-Based Development)과 지속적 배포(CD)를 실현하고 데이터 기반의 비즈니스 의사결정을 가속화하는 **가장 핵심적인 현대 소프트웨어 릴리즈 엔지니어링 및 프로덕트 실험 표준**으로 확립되었으며, 실무 구축 시에는 **LaunchDarkly/Unleash 기반 중앙 플래그 제어 평면, SSE(Server-Sent Events) 스트리밍 및 SDK 인메모리 결정적 해싱을 통한 서브 밀리초 무지연 평가, 장애 시 0.1초 킬 스위치 작동, 토글 부채(Toggle Debt) 방지를 위한 TTL(30일) 만료 및 자동 정리 파이프라인**을 결합하여 릴리즈 리스크를 완벽히 제거

#### 한줄 요약
- 피처 토글은 배포와 출시의 분리, 인메모리 결정적 해시 평가, 긴급 킬 스위치를 통해 릴리스 리스크를 제거하는 핵심 현대 소프트웨어 엔지니어링 기술이다.
