## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **아키텍처 패턴(Architecture Pattern)**: 반복되는 설계 문제에 검증된 구성요소•책임•관계 구조를 재사용하는 해법이다.
- **변경 전파**: 한 구성요소의 수정이 의존 관계를 따라 다른 구성요소의 변경까지 요구하는 현상이다.

</details>

- 정의/개념: **아키텍처 패턴**은 반복 문제의 구성요소•책임•관계를 재사용하는 설계 해법이다.
- 배경/필요성: 화면•업무•상태를 한 구조에 결합하면 **변경 전파** 범위가 확대된다.

#### 한줄 요약

- 반복 설계 문제에 **아키텍처 패턴**을 재사용하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **책임 경계**: 변경 이유와 소유 책임이 같은 기능•데이터를 하나로 묶는 설계 경계이다.
- **결합도(Coupling)**: 한 구성요소의 변경이 다른 요소에 미치는 의존 정도이다.
- **이벤트 주도 아키텍처(Event-Driven Architecture, EDA)**: 이벤트 발행•구독으로 생산자와 소비자를 분리하는 아키텍처이다.
- **경계 간 계약(Boundary Contract)**: 구성요소가 경계를 넘어 교환할 요청•응답•이벤트의 형식과 동작 규칙이다.
- **분산 복잡도(Distributed Complexity)**: 네트워크 지연•부분 실패•중복•순서처럼 분리된 구성요소 간 통신에서 생기는 추가 설계 부담이다.

</details>

- **책임 경계** 분리로 변경 전파 범위를 국소화한다.
- **경계 간 계약**이 패턴 조합의 결합도를 결정한다.
- **EDA**의 비동기 상태 전파는 **분산 복잡도**를 증가시킨다.

#### 한줄 요약

- **책임 경계**, **경계 간 계약**, **결합도**, **분산 복잡도**의 절충이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **모델-뷰-컨트롤러(Model-View-Controller, MVC)**: 화면•입력 제어•업무 상태의 책임을 분리하는 패턴이다.
- **마이크로서비스 아키텍처(Microservice Architecture, MSA)**: 업무별 서비스가 데이터와 배포 경계를 독립적으로 소유하는 아키텍처이다.
- **캡슐화(Encapsulation)**: 상태와 업무 규칙을 경계 안에 숨기고 정해진 동작만 외부에 제공하는 원칙이다.

</details>

| 구성요소 | 책임 |
|:---|:---|
| MVC | **MVC**가 표현•입력과 업무 상태를 **캡슐화** |
| MSA | **MSA**가 업무•데이터•배포 경계 분리 |
| EDA | EDA가 이벤트 생산자•소비자 분리 |

#### 한줄 요약

- **MVC**, **MSA**, **캡슐화**가 책임 경계 분리 방식을 보여 준다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **변경 축(Change Axis)**: 함께 바뀌는 기능•데이터•배포•이벤트의 방향이다.
- **화면 책임 분리**: 표현•입력 제어•업무 상태의 변경 이유를 구분하는 판단이다.
- **업무•데이터 경계 분리**: 독립 배포가 필요한 업무와 데이터 소유권을 서비스로 묶는 판단이다.
- **비동기 전파 분리**: 다수 소비자에게 상태 변화를 이벤트로 전달해 생산자 의존을 줄이는 판단이다.

</details>

```text
┌──────────────────────────────┐
│ 주요 변경 축•품질 요구     │
└──────────────┬───────────────┘
               │
               ├─ 화면•입력•업무 상태
               │          └─▶ [MVC]
               │
               ├─ 업무•데이터•독립 배포
               │          └─▶ [MSA]
               │
               └─ 비동기 전파•다수 소비자
                          └─▶ [EDA]

필요하면 서로 다른 경계에서 패턴 조합
```

### 동작 원리

1. **변경 축**으로 함께 바뀌는 기능•데이터•배포•이벤트를 찾는다.
2. 화면•입력•업무 상태가 함께 바뀌면 **화면 책임 분리**로 MVC를 적용한다.
3. 업무•데이터의 독립 배포가 필요하면 **업무•데이터 경계 분리**로 MSA를 적용한다.
4. 다수 소비자에게 상태 변화를 전달해야 하면 **비동기 전파 분리**로 EDA를 적용한다.

#### 한줄 요약

- **변경 축**에 따라 **화면 책임 분리**, **업무•데이터 경계 분리**, **비동기 전파 분리**를 선택한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **최종 일관성(Eventual Consistency)**: 비동기 갱신이 모두 전달되면 분산 상태가 같은 값으로 수렴하는 성질이다.
- **생산자(Producer)**: 계약에 맞는 이벤트를 발행하는 구성요소이다.
- **소비자(Consumer)**: 계약에 맞는 이벤트를 받아 처리하는 구성요소이다.
- **컨트롤러 비대화(Fat Controller)**: 입력 제어 계층에 업무 규칙과 상태 처리가 몰려 변경•시험이 어려워진 상태이다.
- **관측 비용(Observability Cost)**: 분산 요청의 상태•지연•오류를 로그•지표•추적으로 수집하고 연결하는 데 드는 비용이다.

</details>

| 아키텍처 패턴 | MVC | MSA | EDA |
|:---|:---|:---|:---|
| 적용 기준 | 화면 변경 국소화 | 독립 배포•확장 | 다수 소비자의 비동기 처리 |
| 핵심 특징 | 표현•입력•상태 분리 | 업무•데이터•배포 분리 | **생산자**•**소비자** 분리 |
| 한계 | **컨트롤러 비대화** | 분산 데이터•**관측 비용** | 중복•순서•**최종 일관성** |

> 요약: 화면•업무•이벤트 결합을 각각을 분리한다.

#### 한줄 요약

- 화면은 **MVC**, 독립 배포는 **MSA**, 비동기는 **EDA**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **아키텍처 결정 기록(Architecture Decision Record, ADR)**: 설계 대안•선택 이유•절충을 짧게 남기는 문서이다.
- **소비자 계약 시험(Consumer Contract Test)**: API•이벤트 제공자가 소비자의 기대 필드와 동작을 깨뜨리지 않는지 검증하는 시험이다.
- **트랜잭셔널 아웃박스(Transactional Outbox)**: 업무 데이터와 발행 이벤트를 한 로컬 트랜잭션에 저장한 뒤 전달하는 방식이다.
- **멱등성(Idempotency)**: 같은 이벤트나 요청을 여러 번 처리해도 최종 결과가 한 번 처리한 것과 같은 성질이다.
- **분산 추적(Distributed Tracing)**: 여러 서비스와 이벤트를 거친 요청 경로와 지연을 공통 식별자로 연결해 기록하는 방식이다.
- **배포 시나리오(Deployment Scenario)**: 구성요소를 배포하고 복구하며 확장하는 운영 상황이다.
- **모듈 경계(Module Boundary)**: 높은 응집도를 가진 업무 규칙•데이터를 내부에 묶고 외부 의존을 계약으로 제한하는 경계이다.
- **버전 호환(Version Compatibility)**: API•이벤트가 바뀌어도 기존 소비자가 정한 계약 범위에서 계속 동작하는 성질이다.
- **관측성(Observability)**: 로그•지표•추적 같은 외부 신호로 시스템 내부 상태와 실패 원인을 추론할 수 있는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 품질 요구와 무관한 패턴 선택 | 변경 축•**배포 시나리오** 비교 후 **ADR** 기록 | 선택 근거•절충 명확화 |
| 업무 경계가 불명확한데 MSA로 과도하게 분할 | **모듈 경계** 검증 후 독립 배포 시 분리 | 분산 복잡도 억제 |
| 필드 변경으로 기존 이벤트 소비자 장애 | **버전 호환**•**소비자 계약 시험** 적용 | 이벤트 계약 안정성 확보 |
| 저장 성공 후 이벤트 발행 실패•중복 전달 | **트랜잭셔널 아웃박스**•**멱등성** 적용 | 데이터•이벤트 정합성 향상 |
| 동기•비동기 경로 혼재로 원인 추적 곤란 | 공통 식별자와 **분산 추적**•**관측성** 연결 | 전체 요청 흐름 관측 |

#### 한줄 요약

- **ADR**, **소비자 계약 시험**, **트랜잭셔널 아웃박스**, **관측성**으로 패턴을 검증한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **화면 책임**: 표현•사용자 입력•업무 상태를 MVC로 분리해야 하는 설계 관심사이다.
- **독립 배포**: 한 서비스 변경을 다른 서비스와 함께 배포하지 않고 출시할 수 있는 성질이다.
- **비동기 전파**: 생산자와 다수 소비자 사이의 상태 변화를 이벤트로 전달하는 방식이다.
- **아키텍처 패턴 선택 기준**: 화면 책임•독립 배포•비동기 전파 요구를 비교해 MVC•MSA•EDA 중 적합한 패턴을 고르는 기준이다.

</details>

- **화면 책임**은 **MVC**, **독립 배포**는 **MSA**, **비동기 전파**는 **EDA**를 선택하는 것이 **아키텍처 패턴 선택 기준**이다.

#### 한줄 요약

- 화면•배포•전파 변경 축을 함께 평가하는 것이 핵심이다.
