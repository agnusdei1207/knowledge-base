## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **서비스 메시(Service Mesh)**: 서비스 코드 밖의 프록시 계층에서 서비스 간 통신 정책을 일관되게 실행하는 인프라다.
- **제어 플레인(Control Plane)**: 통신 정책을 검증해 프록시 구성과 인증서로 배포하는 관리 영역이다.

</details>

- 정의/개념: **서비스 메시**는 서비스 간 통신 정책을 제어 플레인에서 배포하고 요청 경로의 프록시에서 일관되게 집행하는 **통신 인프라 계층**이다.
- 배경/필요성: 서비스별 통신 코드 중복으로 **정책 불일치•운영 복잡도가 증가한다**.

#### 한줄 요약

- 서비스 코드 밖에서 **통신 정책을 일관되게 집행**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **데이터 플레인(Data Plane)**: 요청 경로의 프록시가 라우팅•보안•관측 정책을 실행하는 영역이다.
- **프록시(Proxy)**: 서비스 사이의 요청을 중계하면서 통신 정책을 대신 집행하는 구성요소다.

</details>

- **서비스 코드•통신 정책 분리**로 정책 일관성을 확보한다.
- **제어 플레인**의 정책 배포와 데이터 플레인의 요청 집행을 분리한다.
- **데이터 플레인 프록시**의 호출 중계로 보안•관측 정책 일괄 집행이 핵심이다.

#### 한줄 요약

- 중앙 정책 관리와 **프록시 홉 비용**의 절충이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **이스티오(Istio)**: 서비스 메시의 제어 플레인과 트래픽•보안 정책 관리를 제공하는 플랫폼이다.
- **엔보이(Envoy)**: 요청 경로에서 라우팅•보안•관측 정책을 실행하는 응용 계층 프록시다.
- **서비스 탐색(Service Discovery)**: 대상 서비스의 실제 엔드포인트 주소를 찾는 기능이다.
- **텔레메트리(Telemetry)**: 프록시가 통신 상태를 관측하도록 생성하는 메트릭•로그•분산 추적 정보다.

</details>

```text
                         [Istio 제어 플레인]
                                  |
                                  |
[호출 워크로드] -------- [Envoy 데이터 플레인] -------- [대상 워크로드]
                                  |
                                  |
                         [텔레메트리 백엔드]
```

선의 의미: Istio 제어 플레인과 Envoy 데이터 플레인의 선은 정책•구성•인증서 배포 관계, 호출 워크로드와 대상 워크로드를 잇는 선은 Envoy가 중계하는 서비스 통신 관계, Envoy와 텔레메트리 백엔드의 선은 메트릭•로그•분산 추적 전달 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| Istio 제어 플레인 | **정책•프록시 구성•인증서** 배포 |
| 호출 워크로드 | **대상 서비스 요청** 생성 |
| Envoy 데이터 플레인 | **서비스 탐색•라우팅**과 보안•관측 정책 실행 |
| 대상 워크로드 | **허용 요청**의 업무 로직 처리 |
| 텔레메트리 백엔드 | **메트릭•로그•분산 추적** 저장•분석 |

#### 한줄 요약

- 제어 플레인•데이터 플레인•**워크로드•관측 구조**가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **정책 검증**: 제어 플레인이 통신 규칙의 문법•충돌•대상을 확인하는 단계다.
- **구성•인증서 배포**: 검증된 라우팅•보안 정책과 서비스 인증서를 데이터 플레인에 전달하는 단계다.
- **상호 전송 계층 보안(Mutual Transport Layer Security, mTLS)**: 통신 양쪽의 서비스 신원을 인증하고 전송 데이터를 암호화하는 프로토콜이다.
- **인증서(Certificate)**: 공개키와 서비스 신원을 서명해 묶어 mTLS 상호 인증에 사용하는 전자 문서다.
- **텔레메트리 백엔드(Telemetry Backend)**: 프록시가 보낸 메트릭•로그•분산 추적을 저장•분석하는 관측 시스템이다.
- **서비스 인가(Service Authorization)**: 인증된 호출 서비스가 대상 경로•메서드에 접근할 권한이 있는지 정책으로 판정하는 절차다.

</details>

```text
제어 경로

[운영자 통신 정책]
         │
         ▼
[1. 정책 검증]
         │
         ▼
[2. 구성•인증서 배포]
         │
         ▼
[데이터 플레인 구성 반영]

요청 경로

[호출 워크로드 요청]
         │
         ▼
[3. 서비스 탐색•라우팅]
         │
         ▼
[4. mTLS 신원•인가 판정]
         ├─ 거부 ─▶ [정책 오류 반환]
         │ 허용
         ▼
[대상 워크로드 처리]
         │
         ▼
[5. 텔레메트리 기록]
         │
         ▼
[서비스 응답 반환]
```

**동작 원리**

- **1. 정책 검증**: 통신 규칙의 문법•충돌•대상을 확인한다.
- **2. 구성•인증서 배포**: 검증 구성을 프록시에 반영한다.
- **3. 서비스 탐색•라우팅**: 대상 엔드포인트를 선택한다.
- **4. mTLS 신원•인가 판정**: 호출 신원과 접근 권한 검사이다.
- **5. 텔레메트리 기록**: 호출 결과를 관측 백엔드에 저장한다.

#### 한줄 요약

- 제어 구성 배포와 데이터 경로 **정책 집행 분리**가 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **사이드카 모드(Sidecar Mode)**: 각 워크로드에 전용 Envoy 프록시를 함께 배치하는 방식이다.
- **앰비언트 모드(Ambient Mode)**: 노드별 ztunnel과 선택적 웨이포인트를 여러 워크로드가 공유하는 방식이다.
- **제로 트러스트 터널(zero-trust tunnel, ztunnel)**: 앰비언트 모드에서 4계층 라우팅•신원•mTLS를 처리하는 노드 프록시다.
- **웨이포인트 프록시(Waypoint Proxy)**: 공유 응용 계층 정책을 실행하는 프록시다.

</details>

| 서비스 메시 배치 | 사이드카 모드 | 앰비언트 모드 |
|:---|:---|:---|
| 적용 기준 | 워크로드별 **세밀한 정책** | 사이드카 **운영 비용 절감** |
| 핵심 특징 | 워크로드별 **Envoy 전용 프록시** | 노드별 **ztunnel**•선택적 웨이포인트 공유 |
| 한계 | 프록시 수만큼 **자원 증가** | 공유 프록시 **장애 범위 확대** |

> 요약: **정책 세분성**과 **프록시 비용**으로 배치 방식을 선택한다.

#### 한줄 요약

- 세밀 정책은 사이드카, 비용 절감은 **앰비언트**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **카나리아 적용(Canary Rollout)**: 정책을 일부 워크로드•트래픽에 먼저 적용해 이상 여부를 확인한 뒤 확대하는 방식이다.
- **구성 배포 지연(Configuration Propagation Delay)**: 정책 변경부터 모든 데이터 플레인 프록시에 반영되기까지의 시간이다.
- **카디널리티(Cardinality)**: 메트릭 라벨 조합으로 생성되는 서로 다른 시계열의 개수다.
- **트래픽 가중치(Traffic Weight)**: 전체 요청 중 각 서비스 버전으로 보낼 비율을 정하는 값이다.
- **사전 검증(Pre-deployment Validation)**: 배포 전에 정책 문법과 충돌 및 대상을 검사하는 통제다.
- **복원본(Rollback Copy)**: 실패 시 되돌릴 마지막 정상 구성이다.
- **벤치마크(Benchmark)**: 같은 부하에서 지연•프로세서•메모리를 측정해 메시 배치 방식의 비용을 비교하는 시험이다.
- **인증서 자동 순환(Certificate Rotation)**: 만료 전에 인증서를 교체하는 운영 방식이다.
- **시각 동기화(Time Synchronization)**: 노드 시각을 맞춰 인증서 유효기간 판정 오류를 막는 방식이다.
- **라벨 허용 목록(Label Allowlist)**: 수집할 메트릭 라벨을 제한하는 목록이다.
- **샘플링(Sampling)**: 전체 사건 중 일부만 기록하는 수집 방식이다.
- **보존기간(Retention Period)**: 텔레메트리를 저장하는 기간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잘못된 정책이 전체 서비스 통신을 차단 | **사전 검증•카나리아 적용•복원본** 유지 | **정책 장애 범위** 축소 |
| 제어 플레인 장애와 구성 배포 지연을 미관측 | **마지막 정상 구성•배포 지연** 감시 | 관리 장애 중 **데이터 경로** 지속 |
| 프록시 홉으로 지연•CPU•메모리 증가 | **벤치마크**로 사이드카•앰비언트 적용 범위 선택 | 필요한 **정책 비용** 만 부담 |
| 인증서 만료•시간 오차로 mTLS 통신 실패 | **자동 순환•만료 경보•시각 동기화** | **서비스 신원** 연속성 확보 |
| 고카디널리티 텔레메트리로 저장 비용 폭증 | **라벨 허용 목록•샘플링•보존기간** 적용 | **관측 비용** 통제 |

#### 한줄 요약

- 정책 카나리아•인증서 순환•**관측 비용**을 통제한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **7계층(Layer 7, L7) 정책**: 경로•메서드 등 응용 프로토콜 정보를 해석해 적용하는 세밀한 통신 정책이다.
- **4계층(Layer 4, L4) 보안**: 연결 주소•포트와 서비스 신원을 기준으로 적용하는 전송 계층 보안이다.

</details>

- L7 세밀 정책은 **사이드카•웨이포인트**, L4 보안은 **ztunnel**을 선택한다.

#### 한줄 요약

- L7 정책은 사이드카•웨이포인트, L4는 **ztunnel**가 핵심이다.
