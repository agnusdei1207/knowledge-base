## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컨텍스트 맵 및 ACL(Context Map & ACL)**: 바운디드 컨텍스트 간의 상하류(U/D) 관계를 도식화하고 타 도메인 모델이 내부를 오염시키지 않도록 격리 변환하는 계층.
- **용어 충돌 및 스키마 비대화(Semantic Collision & Bloated Schema)**: 동일 단어(예: '회원')가 마케팅/정산/물류에서 서로 다른 의미를 가짐에도 단일 테이블에 수백 개 컬럼을 억지로 우겨넣는 안티패턴.

</details>

- 정의/개념: 도메인 모델과 보편적 언어가 단일한 의미를 유지하도록 격리하고 **컨텍스트 맵과 ACL(오염방지계층)** 로 상호 통합하는 DDD 전략적 설계 경계
- 배경/필요성: 전사 통합 단일 거대 모델 구축 시 발생하는 **도메인 용어 의미 충돌 및 스키마 비대화와 결합도 폭증** 직면

#### 한줄 요약

- 도메인 용어의 의미가 바뀌는 지점에 명시적 경계를 정의하여 모델 일관성을 보장하는 DDD 전략 패턴

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **업스트림/다운스트림(Upstream/Downstream)**: 컨텍스트 간 데이터 흐름에서 공급자(상류, Upstream)와 소비자(하류, Downstream)의 의존 방향 관계.
- **오염 방지 계층(ACL, Anti-Corruption Layer)**: 업스트림의 모델·구조가 다운스트림 도메인 모델을 오염하지 않도록 경계에서 번역·변환하는 격리 계층.

</details>

- 경계 내부에서 **보편적 언어** 의미를 일관되게 유지
- **콘웨이의 법칙** 대상 따라 1개 팀이 1개 바운디드 컨텍스트를 독자 소유하는 팀-컨텍스트 정렬
- 컨텍스트 간 통합 시 **ACL·공유 커널(Shared Kernel)·공개 호스트 서비스(OHS)** 등 관계 패턴 적용

#### 한줄 요약

- 경계 내 용어 일관성 유지, 팀-컨텍스트 1:1 정렬, ACL 기반 경계 간 통합

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **공유 커널(Shared Kernel)**: 두 컨텍스트가 핵심 도메인 모델 일부를 공동으로 관리하는 결합 방식으로 변경 시 상호 합의가 필요.
- **공개 호스트 서비스(OHS, Open Host Service)**: 업스트림이 복수의 다운스트림에 표준화된 REST API·이벤트 인터페이스를 공개하는 통합 방식.

</details>

```text
[ 컨텍스트 맵 구조 ]
업스트림 컨텍스트 (결제)
└─ OHS: 표준 REST API / 도메인 이벤트 발행
   │
컨텍스트 맵 경계
   │
ACL (번역·변환 계층)
   │
다운스트림 컨텍스트 (주문)
└─ ACL에서 번역된 데이터를 내부 모델에 적용
```

선의 의미: 업스트림에서 ACL로의 화살표는 OHS 기반 데이터 공급 관계, ACL에서 다운스트림으로의 화살표는 번역된 데이터의 내부 반영 관계

| 구성요소 | 책임 |
|:---|:---|
| **업스트림 (공급자)** | 도메인 이벤트 발행·API 제공 |
| **컨텍스트 맵** | 컨텍스트 간 의존 방향·통합 패턴 시각화 |
| **ACL** | 업스트림 모델을 다운스트림 도메인 언어로 번역 |
| **다운스트림 (소비자)** | ACL을 통해 오염 없이 번역된 데이터를 내부 모델에 반영 |

#### 한줄 요약

- 업스트림이 OHS로 데이터를 제공하면 ACL이 번역하여 다운스트림 도메인 모델에 안전하게 반영

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **이벤트 기반 통합(Event-Driven Integration)**: 컨텍스트 간 직접 API 호출 대신 메시지 브로커를 통한 비동기 이벤트로 통합하여 결합도를 최소화하는 방식.

</details>

```text
1. 업스트림 상태 변경 (결제 완료)
   └─ 도메인 이벤트 발행 (PaymentCompleted)
   │
   ▼
2. 이벤트 브로커(Kafka) 전달
   │
   ▼
3. 다운스트림 ACL 이벤트 수신
   └─ 업스트림 모델을 다운스트림 도메인 언어로 번역
   │
   ▼
4. 다운스트림 도메인 상태 반영
   └─ 주문 상태 → '배송 준비' 업데이트
```

**동작 원리**

1. **이벤트 발행**: 업스트림이 상태 변경 시 도메인 이벤트를 메시지 브로커에 발행
2. **ACL 수신**: 다운스트림의 ACL이 이벤트를 수신하여 자체 도메인 언어로 번역
3. **로컬 반영**: 번역된 데이터를 다운스트림 자체 DB에 저장하여 도메인 모델 일관성 유지
4. **격리 완료**: 업스트림 구조 변경이 다운스트림 도메인 모델에 직접 영향을 미치지 않음

#### 한줄 요약

- 이벤트 발행→ACL 번역→다운스트림 도메인 반영으로 컨텍스트 간 결합도를 최소화하며 통합

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전사 공유 모델 vs 바운디드 컨텍스트**: 전체 조직이 단일 도메인 모델을 공유하는 방식과 컨텍스트별 독립 모델을 유지하는 방식의 대비.

</details>

| 구분 | 전사 공유 모델 | 바운디드 컨텍스트 |
|:---|:---|:---|
| 용어 관리 | 전사 단일 용어 공유로 의미 충돌 발생 | **경계 내에서 용어의 단일 의미 보장** |
| 데이터 소유권 | 단일 DB를 다수 팀이 공유·수정 | **컨텍스트별 독립 DB·단일 팀 소유** |
| 배포 독립성 | 단일 배포로 전체 영향 | API·이벤트(ACL) 기반 **독립 배포** |

#### 한줄 요약

- 전사 공유 모델의 의미 충돌·배포 결합 문제를 바운디드 컨텍스트의 경계 분리와 ACL로 해소

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **콘웨이의 법칙(Conway's Law)**: 시스템 설계는 그것을 개발하는 조직의 소통 구조를 따르므로, 바운디드 컨텍스트 경계와 팀 경계를 정렬해야 한다는 법칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기술 중심으로 DB를 분리하여 분산 모놀리스 발생 | **이벤트 스토밍** 기반 도메인 용어 의미 변환 경계를 먼저 도출 | 비즈니스 의미 기반 경계 분리로 분산 모놀리스 방지 |
| 업스트림 API 변경으로 다운스트림 코드 연쇄 수정 | **ACL** 번역 계층으로 업스트림 구조 변경을 격리 | 업스트림 변경의 다운스트림 도메인 파급 차단 |
| 복수 팀이 단일 컨텍스트를 동시 수정하여 충돌 | **콘웨이의 법칙** 기반 1팀=1컨텍스트 책임 부여 | 의사결정 병목 해소 및 책임 명확화 |

#### 한줄 요약

- 경계 도출은 이벤트 스토밍으로, 업스트림 변경 파급은 ACL로, 팀 충돌은 콘웨이 법칙 기반 1:1 정렬로 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **바운디드 컨텍스트 도출 기준**: 도메인 용어의 의미 차이·배포 주기 차이·팀 소유권 차이를 기준으로 경계 설정을 결정하는 판단 기준.

</details>

- 용어 의미가 달라지고 팀 소유권이 구분되는 지점에 **바운디드 컨텍스트** 경계를 설정하고 **ACL** 기반 통합

#### 한줄 요약

- MSA 서비스 분리의 기준을 기술(DB) 대신 도메인 용어 의미 변환 경계에 두고 ACL로 통합
