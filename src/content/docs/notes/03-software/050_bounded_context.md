## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **바운디드 컨텍스트(Bounded Context)**: 한 도메인 모델과 공통 언어의 의미가 일관되게 적용되는 명시적 경계이다.
- **도메인 모델(Domain Model)**: 업무 개념•관계•규칙을 실행 가능한 구조로 표현한 모델이다.
- **공통 언어(Ubiquitous Language)**: 경계 안의 대화•모델•코드에서 같은 뜻으로 쓰는 업무 용어이다.

</details>

- 정의/개념: **바운디드 컨텍스트**는 하나의 **도메인 모델**과 **공통 언어**가 같은 의미로 적용되는 경계이다.
- 배경/필요성: 전사 단일 모델이 여러 의미를 공유하면 업무 용어•규칙 충돌이 발생한다.

#### 한줄 요약

- **도메인 모델**과 **공통 언어**의 **바운디드 컨텍스트**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **경계 내부**: 하나의 공통 언어와 도메인 모델이 같은 의미로 적용되는 범위이다.
- **컨텍스트 맵(Context Map)**: 바운디드 컨텍스트 사이의 의존•협력•번역 관계를 나타낸 지도이다.
- **번역 계약**: 서로 다른 모델의 의미를 섞지 않고 데이터•행위를 변환하는 규칙이다.

</details>

- **경계 내부**에서 공통 언어•모델 의미 일관성을 유지한다.
- 경계별 업무 목적에 따라 동일 용어를 독립적으로 모델링한다.
- **컨텍스트 맵**과 **번역 계약**으로 경계 간 의존 방향을 명시한다.

#### 한줄 요약

- **경계 내부**, **컨텍스트 맵**, **번역 계약**이 의미 일관성을 보호한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **업스트림(Upstream)**: 모델 계약을 제공하는 컨텍스트이다.
- **다운스트림(Downstream)**: 업스트림의 모델 계약을 소비하는 컨텍스트이다.
- **오염 방지 계층(Anti-Corruption Layer, ACL)**: 외부 모델과 용어가 내부 모델에 침투하지 않도록 변환하는 계층이다.
- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능을 정해진 요청•응답 계약으로 호출하게 하는 인터페이스이다.
- **공개 계약(Published Contract)**: 업스트림이 외부 컨텍스트에 제공하는 API•이벤트의 의미•필드•버전 규칙이다.
- **불변 조건(Invariant)**: 다운스트림 모델이 상태 변경 전후에 반드시 유지해야 하는 업무 규칙이다.

</details>

```text
[업스트림 컨텍스트]
          |
   [컨텍스트 맵]
          |
 [오염 방지 계층]
          |
[다운스트림 컨텍스트]
```

선의 의미: 컨텍스트 맵은 업스트림과 다운스트림의 의존 관계를 명시하고, 오염 방지 계층은 업스트림의 공개 계약을 다운스트림 모델의 언어로 격리해 번역한다.

| 구성요소 | 책임 |
|:---|:---|
| 업스트림 컨텍스트 | **업스트림**이 자체 모델•**공개 계약**과 **API** 소유 |
| 컨텍스트 맵 | 경계 간 의존•협력 관계 명시 |
| 오염 방지 계층 | **ACL**이 외부 계약을 내부 공통 언어로 번역 |
| 다운스트림 컨텍스트 | **다운스트림**이 자체 모델•**불변 조건** 유지 |

#### 한줄 요약

- **업스트림**, **공개 계약**, **ACL**, **다운스트림**의 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **공개 계약 이벤트 발행**: 업스트림 변경 사실을 공개된 필드•의미•버전에 맞춰 전달하는 동작이다.
- **계약 버전•호환성 검증**: 다운스트림이 이해할 수 있는 계약 버전과 필드인지 확인하는 동작이다.
- **내부 언어 번역**: 오염 방지 계층이 외부 용어와 상태를 다운스트림 모델 의미로 바꾸는 동작이다.
- **불변 조건 검증**: 번역한 변경이 다운스트림의 업무 규칙을 깨뜨리지 않는지 확인하는 동작이다.
- **다운스트림 상태 반영**: 검증한 변경을 내부 모델에 멱등하게 적용하는 동작이다.

</details>

```text
[업스트림 상태 변경]
          |
          v
+----------------------------+
| 1. 공개 계약 이벤트 발행   |
+----------------------------+
          |
          v
+----------------------------+
| 2. 계약 버전•호환성 검증   |---- 실패 ----> [격리•재처리]
+----------------------------+
          |
          v
+----------------------------+
| 3. 내부 언어 번역          |
+----------------------------+
          |
          v
+----------------------------+
| 4. 불변 조건 검증          |---- 실패 ----> [업무 오류 처리]
+----------------------------+
          |
          v
+----------------------------+
| 5. 다운스트림 상태 반영    |
+----------------------------+
          |
          v
[경계별 모델 의미 유지]
```

**동작 원리**

1. **공개 계약 이벤트 발행**으로 변경 사실을 공개 형식으로 전달한다.
2. **계약 버전•호환성 검증**으로 소비 가능한 계약인지 확인한다.
3. **내부 언어 번역**으로 외부 의미를 내부 모델로 변환한다.
4. **불변 조건 검증**으로 내부 규칙에 맞는 변경만 허용한다.
5. **다운스트림 상태 반영**으로 검증 결과를 멱등하게 적용한다.

> 요약: 경계별 모델은 독립 유지하고 **공개 계약**과 **오염 방지 계층**으로 연결한다.

#### 한줄 요약

- **공개 계약 이벤트 발행**부터 **다운스트림 상태 반영**까지의 흐름이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단일 통합 모델**: 여러 업무가 하나의 공통 데이터•용어 구조를 공유하는 모델이다.
- **분산 일관성(Distributed Consistency)**: 서로 다른 컨텍스트 상태가 계약 전달과 비동기 반영을 거쳐 허용된 값으로 맞춰지는 성질이다.
- **연쇄 변경**: 공유 모델의 한 변경이 여러 업무 컨텍스트의 동시 수정을 요구하는 현상이다.

</details>

| 도메인 모델 경계 | 바운디드 컨텍스트 분리 | 단일 통합 모델 |
|:---|:---|:---|
| 적용 기준 | 용어•규칙•변경 책임 상이 | 의미•변경 주기 동일 |
| 핵심 특징 | 업무별 모델•계약•번역 경계 | **단일 통합 모델**의 공통 모델 공유 |
| 한계 | 번역•계약•**분산 일관성** 비용 | 의미 충돌•**연쇄 변경** |

> 요약: **변경 책임**이 같으면 통합하고 다르면 **컨텍스트 분리**가 핵심이다.

#### 한줄 요약

- 의미•책임이 같으면 통합, 다르면 **컨텍스트 분리**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **데이터 소유권(Data Ownership)**: 한 컨텍스트가 특정 데이터의 변경 권한과 책임을 단독으로 갖는 원칙이다.
- **모델 오염(Model Corruption)**: 외부 컨텍스트 용어•구조가 번역 없이 퍼져 내부 모델 의미가 흐려지는 현상이다.
- **스키마 버전(Schema Version)**: 계약 필드와 의미의 변경 단계를 구분해 소비자가 호환 여부를 판단하는 식별자이다.
- **멱등성(Idempotency)**: 같은 계약 이벤트를 여러 번 처리해도 결과가 한 번 처리한 것과 같게 유지되는 성질이다.
- **스키마 결합(Schema Coupling)**: 여러 컨텍스트가 같은 데이터베이스 구조에 직접 의존해 한쪽 변경이 다른 쪽 수정을 강제하는 상태이다.
- **명시적 번역(Explicit Translation)**: 외부 계약의 필드•용어•상태를 내부 공통 언어와 모델로 바꾸는 규칙을 경계에 분명히 구현하는 방식이다.
- **호환 규칙(Compatibility Rule)**: 계약 변경이 기존 소비자의 기대를 깨지 않게 하는 규칙이다.
- **계약 시험(Contract Test)**: 계약 호환 규칙을 자동 검증하는 시험이다.
- **대사(Reconciliation)**: 컨텍스트 상태를 비교해 불일치를 바로잡는 절차이다.
- **제한 재시도(Bounded Retry)**: 전송 실패를 정한 횟수 안에서 다시 처리하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 조직도만 기준으로 경계를 나눠 업무 의미가 중첩 | 용어 의미•변경 책임으로 경계 도출 | 업무 의미 보존 |
| 컨텍스트가 데이터베이스를 공유해 **스키마 결합** | **데이터 소유권**•공개 계약 기반 연동 | 독립 변경 확보 |
| 외부 모델을 번역 없이 내부에서 직접 사용 | 오염 방지 계층에서 **명시적 번역** | **모델 오염** 방지 |
| 공개 계약 변경으로 다운스트림 호환성 파괴 | **호환 규칙**과 **스키마 버전**•**계약 시험** | 소비자 중단 방지 |
| 계약 이벤트 중복•지연으로 경계 간 상태 불일치 | **멱등성**•**대사**와 **제한 재시도** | 분산 일관성 복구 |

#### 한줄 요약

- **데이터 소유권**, **명시적 번역**, **계약 시험**, **멱등성**을 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **변경 책임**: 업무 규칙과 데이터 변경을 결정하고 결과를 소유하는 조직•모델의 책임이다.
- **컨텍스트 통합**: 용어 의미와 변경 주기가 같을 때 별도 경계의 번역 비용을 없애는 결정이다.
- **컨텍스트 경계 선택 기준**: 용어 의미와 변경 책임을 비교해 컨텍스트 분리와 통합 중 적합한 구조를 고르는 기준이다.

</details>

- 용어 의미와 **변경 책임**이 다르면 바운디드 컨텍스트를 분리하고, 같으면 **컨텍스트 통합**을 선택하는 것이 **컨텍스트 경계 선택 기준**이다.

#### 한줄 요약

- 의미와 변경 책임을 함께 평가하는 것이 핵심이다.
