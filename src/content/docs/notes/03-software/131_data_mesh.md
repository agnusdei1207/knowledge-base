## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 메시(Data Mesh)**: Zhamak Dehghani가 제안한 패러다임으로, 모놀리식 중앙 데이터 레이크를 해체하고 현업 도메인이 데이터 제품(Data Product)을 직접 소유·서빙하는 탈중앙 아키텍처.
- **4대 핵심 원칙**: Domain Ownership(도메인 소유권), Data as a Product(데이터 제품화), Self-serve Platform(셀프서비스 인프라), Federated Governance(연합 거버넌스).

</details>

- 정의/개념: 중앙 집중식 데이터 관리 병목을 해소하기 위해 **도메인 중심 소유권, Data-as-a-Product, 셀프서비스 플랫폼, 연합 거버넌스 4대 원칙을 적용**하는 탈중앙 데이터 아키텍처
- 배경/필요성: 단일 중앙 데이터팀에 모든 파이프라인 구축이 집중되어 발생하는 **데이터 수집 요청 적체, 도메인 맥락 부재에 따른 품질 저하 및 파이프라인 마비 해결 불가**

#### 한줄 요약
- 데이터 소유권을 도메인 팀에 분산하고 제품화하여 전사 데이터 민주화를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Data as a Product**: 데이터를 단순 부산물이 아닌 스키마, SLA, API 문서, 거버넌스를 완비한 완결된 소프트웨어 제품으로 취급.
- **Federated Computational Governance**: 중앙의 표준 정책(보안/마스킹/품질)을 수동 승인이 아닌 Policy-as-Code로 자동 강제 집행.

</details>

- 현업 비즈니스 도메인(주문, 결제, 회원)에 **데이터 소유권과 품질 책임을 분산 부여(Decentralized)**
- 검색성, 신뢰성, 상호운용성을 갖춘 **독립적 데이터 제품(Data-as-a-Product) 서빙**
- 도메인 팀이 인프라를 자급자족 프로비저닝하는 **셀프서비스 데이터 플랫폼 구축**

#### 한줄 요약
- 도메인 주도 소유권과 데이터 제품화를 통해 전사 데이터 분석의 확장성을 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Data Product Quantum**: 도메인 코드, 데이터(폴리글랏 스토리지), 메타데이터, 입출력 포트가 캡슐화된 독립 배포 단위.

</details>

```text
[데이터 메시 4대 원칙 기반 아키텍처]
|-- 1. Domain Data Products (현업 도메인 팀별 독립 데이터 제품)
|   |-- [주문 도메인 제품] -> 코드 + 데이터(S3) + 스키마 + SQL/REST Output Port
|   |-- [결제 도메인 제품] -> 코드 + 데이터(S3) + 스키마 + SQL/REST Output Port
|   `-- [물류 도메인 제품] -> 코드 + 데이터(S3) + 스키마 + SQL/REST Output Port
|-- 2. Self-Serve Data Platform Layer (셀프서비스 데이터 인프라)
|   `-- 원클릭 S3/Spark/Airflow 템플릿 프로비저닝 및 공통 모니터링
`-- 3. Federated Computational Governance Layer (연합형 전산 거버넌스)
    `-- Policy-as-Code (자동 권한/PII 마스킹) + Data Contract + 통합 카탈로그
```

선의 의미: 계층 및 현업 도메인이 Data Product를 독립 생성하고 하단의 셀프서비스 플랫폼과 연합 거버넌스가 이를 지원하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| 도메인 소유권 (Domain) | 현업 도메인 팀이 **데이터 파이프라인 생성, 품질 검증, 생명주기를 직접 소유** | 비즈니스 맥락 유지 |
| 데이터 제품 (Product) | 스키마, SLO, API 문서, 데이터 계약을 완비하여 **소비자에게 신뢰성 있게 서빙** | Data Contract 보증 |
| 셀프서비스 플랫폼 | 도메인 팀이 복잡한 인프라 관리 없이 **파이프라인과 스토리지를 자급 생성하도록 지원** | 플랫폼 엔지니어링 |
| 연합 거버넌스 | 전사 카탈로그, PII 마스킹, 접근 제어 정책을 **코드로 자동 집행(Policy-as-Code)** | 자율과 통제의 조화 |

#### 한줄 요약
- 도메인 소유권, 데이터 제품, 셀프서비스 플랫폼, 연합 거버넌스가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 제품 배포 5단계**: 도메인 경계 식별 $\to$ 데이터 계약 체결 $\to$ 셀프서비스 배포 $\to$ 거버넌스 자동 검증 $\to$ 카탈로그 전사 공개.

</details>

```text
도메인 팀의 신규 데이터 제품 개발 요청
        │
   [도메인 경계 식별] 비즈니스 바운디드 컨텍스트(Bounded Context) 기준으로 도메인 소유권 확정
        │
   [데이터 계약 체결] 소비자가 요구하는 스키마, 데이터 타입, SLA, 갱신 주기를 Data Contract로 공식화
        │
   [셀프서비스 배포] 플랫폼 팀의 표준 IaC 템플릿으로 S3 버킷 및 Spark 잡 원클릭 인프라 배포
        │
   [거버넌스 자동 검증] CI/CD 파이프라인에서 PII 마스킹 및 스키마 유효성을 코드로 자동 검증
        │
   [전사 카탈로그 공개] OpenMetadata/DataHub에 데이터 제품 메타데이터와 출력 포트를 등록하여 공개
```

#### 한줄 요약
- 경계 식별 → 계약 체결 → 셀프서비스 배포 → 거버넌스 검증 → 카탈로그 공개 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙형 레이크 vs 데이터 메시**: 단일 데이터팀이 모든 수집을 독점하는 중앙형 구조와 도메인 팀이 분산 소유하는 메시 구조.

</details>

| 비교 항목 | 중앙 집중식 데이터 레이크/DW | 데이터 메시 (Data Mesh) |
|:---|:---|:---|
| 아키텍처 모델 | **중앙 집중형 모놀리스 (Centralized)** | **도메인 분산형 탈중앙화 (Decentralized)** |
| 파이프라인 책임 | **중앙 데이터 엔지니어링 팀이 전담** | **각 비즈니스 도메인(주문, 결제 등) 팀이 직접 전담**|
| 데이터 개념 정의 | 단순 원천 파일 덤프 또는 중앙 테이블 | **SLA와 문서가 포함된 완결된 데이터 제품(Product)** |
| 확장성 한계 | 중앙 팀 병목으로 인한 파이프라인 적체 | **도메인 단위 자율 확장(Scale-Out) 가능** |

#### 한줄 요약
- 소규모 조직은 중앙형 레이크, 복잡한 대규모 조직은 데이터 메시 아키텍처를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Data Silo Risk**: 거버넌스 통제 없이 도메인 자율권만 부여하여 팀별로 데이터가 고립되고 인프라 비용이 중복 폭증하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 도메인별 분산 적재로 인한 데이터 사일로(Data Silo) 고립 | **전사 메타데이터 카탈로그(OpenMetadata/DataHub) 연동 의무화** | 전사 데이터 검색성 및 계보 확보 |
| 도메인 팀별 중복 인프라 프로비저닝으로 클라우드 비용 폭증 | **셀프서비스 플랫폼에 중앙 FinOps 모니터링 및 쿼터제 적용** | 불필요한 중복 인프라 비용 차단 |
| 도메인 팀의 데이터 품질 무관심으로 인한 왜곡 데이터 유입 | **Data Contract 체결 및 위반 시 파이프라인 자동 차단 훅 설정** | 데이터 품질 SLA 100% 보장 |
| 도메인 개발자의 데이터 엔지니어링 역량 부족 | **플랫폼 팀의 표준 골든 패스(Golden Path) 템플릿 제공** | 진입 장벽 완화 및 셀프서비스 가속 |

#### 한줄 요약
- 전사 카탈로그 연동, FinOps 비용 통제, Data Contract 품질 자동화, 골든 패스로 정착시킨다.

## Ⅶ. 결론

- 소유권 분산은 **데이터 메시**, 통제는 **연합 거버넌스** 선택

#### 한줄 요약
- 데이터 메시는 데이터 소유권을 비즈니스 도메인에 분산하고 제품화하여 전사적 병목을 해소하는 현대 데이터 엔지니어링의 핵심 조직·기술 패러다임이다.
