## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **오염 분석(Taint Analysis)**: 외부 입력 소스(Source)로부터 데이터 정화(Sanitizer) 없이 민감 싱크(Sink: SQL 쿼리, 시스템 명령어)로 도달하는 오염 데이터 흐름을 추적하는 기법.
- **추상 구문 트리(AST, Abstract Syntax Tree)**: 소스코드의 문법 구조를 계층적 트리 노드로 파싱하여 의미론적 제어 흐름 및 데이터 흐름 분석을 가능하게 하는 자료구조.

</details>

- 정의/개념: 소스코드를 실행하지 않고 **추상 구문 트리(AST) 및 오염 분석(Taint Analysis)** 을 통해 코딩/빌드 단계에서 보안 약점을 탐지하는 화이트박스 보안 테스팅 기법
- 배경/필요성: 배포 후 런타임 보안 사고 발생 시 **취약점 수정 비용 급증 및 운영 데이터 유출 피해 위험** 직면

#### 한줄 요약

- 코드를 실행하지 않고 구문 파싱과 오염 흐름 추적으로 소스코드 내 보안 약점을 조기에 탐지

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **화이트박스 테스팅(White-Box Testing)**: 소스코드의 내부 구조, 제어 흐름, 변수 선언을 직접 들여다보며 논리적 결함과 취약점을 검증하는 기법.
- **오탐율(False Positive Rate)**: 실제 보안 위협이 아님에도 정적 분석 룰셋에 의해 취약점으로 오판되는 비율.

</details>

- 소스코드 전체를 분석하는 **화이트박스(White-Box) 기반 전수 점검**
- 개발/빌드 단계에 즉각 적용하는 **시프트 레프트(Shift-Left) 보안 내재화**
- 실행 컨텍스트 부재로 인한 **오탐(False Positive) 억제 및 커스텀 룰셋 튜닝 필요**

#### 한줄 요약

- 화이트박스 전수 분석으로 정확한 코드 라인을 식별하되 오탐 필터링과 룰셋 최적화가 필수

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **소스-싱크-새니타이저(Source-Sink-Sanitizer)**: 외부 입력 유입점(Source), 취약점 발생 실행점(Sink), 유효성 검증 및 이스케이프 처리기(Sanitizer)로 구성된 오염 분석 모델.

</details>

```text
[ SAST 정적 분석 아키텍처 구조도 ]

  [ 소스코드 파일 ] ──► [ 구문 파서 (Lexer/Parser) ] ──► [ 추상 구문 트리 (AST) ]
                                                              │
                                                              ▼
  [ 보안 룰셋 (KISA/CWE) ] ─────────────────────────► [ 제어/데이터 흐름 분석기 ]
                                                              │
                                                              ▼
  [ 품질 게이트 판정 ] ◄── [ 오탐 예외 억제(Suppress) ] ◄── [ 오염 분석 엔진 (Taint) ]
```

선의 의미: 소스코드에서 AST 생성, 룰셋 결합, 오염 데이터 흐름 추적 및 게이트 판정 파이프라인.

| 구성요소 | 책임 |
|:---|:---|
| 구문 파서 (Parser) | 소스코드를 파싱하여 **추상 구문 트리(AST) 및 제어 흐름 그래프(CFG) 생성** |
| 오염 분석 엔진 (Taint) | 입력 소스(Source)부터 실행 싱크(Sink)까지 **미정화 데이터 흐름 추적** |
| 규칙 엔진 (Rule Engine) | KISA 47개 보안약점 및 CWE/OWASP 룰셋과 **패턴 매칭 검증** |
| 결과 필터 (Suppressor) | 주석 및 설정 기반으로 **오탐(False Positive) 항목 필터링 및 억제** |

#### 한줄 요약

- 파서가 AST를 생성하고 오염 분석 엔진이 룰셋과 대조하여 취약점 라인을 검출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **KISA SW 개발보안 가이드**: 행정안전부 및 KISA가 규정한 입력데이터 검증, 보안기능, 시간 및 상태 등 47개 소프트웨어 보안약점 기준.

</details>

```text
[ SAST 실행 및 품질 게이트 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 코드 파싱: AST 및 CFG/DFG 생성     │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 오염 경로 추적: Source → Sink 분석  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 룰셋 대조: KISA/OWASP 보안약점 매칭 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 품질 게이트 판정: 위험도 임계치 검사│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 코드 파싱: 소스코드를 분석하여 문법 트리(AST)와 제어 흐름(CFG), 데이터 흐름(DFG)을 추출.
2. 오염 경로 추적: 사용자 입력(HTTP 파라미터)이 적절한 검증/새니타이징 없이 DB 쿼리나 파일 I/O로 전달되는지 추적.
3. 룰셋 대조: SQL Injection, XSS, 하드코딩된 비밀키 등 표준 보안 룰셋 위반 여부를 대조.
4. 품질 게이트 판정: 심각도(Critical/High) 취약점 검출 시 CI/CD 빌드를 차단하고 리포트를 생성.

#### 한줄 요약

- 코드 파싱 $\to$ 오염 경로 추적 $\to$ 룰셋 대조 $\to$ 빌드 게이트 판정의 4단계 자동화 파이프라인

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DAST(Dynamic Application Security Testing)**: 실행 중인 웹 애플리케이션을 외부에서 모의 침투하여 런타임 취약점을 탐지하는 블랙박스 테스팅.

</details>

| 구분 | 정적 분석 (SAST) | 동적 분석 (DAST) |
|:---|:---|:---|
| **적용 기준** | 개발 및 CI/CD 빌드 단계 화이트박스 검증 | 스테이징 및 운영 배포 후 블랙박스 침투 검증 |
| **핵심 특징** | **정확한 코드 취약 라인 식별 및 시프트 레프트** | **런타임 환경설정 및 인증 오류 실시간 탐지** |
| **한계** | 비실행 분석으로 인한 상대적 오탐(False Positive) 발생 | 소스코드 미확인으로 구체적 수정 위치 파악 지연 |

#### 한줄 요약

- SAST는 코드 내부 결함을 조기에 전수 점검하고, DAST는 실행 환경의 실제 침투 가능성을 상호 보완 검증

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **증분 분석(Incremental Analysis)**: 전체 코드베이스 대신 Git 커밋/PR에서 변경된 파일과 영향 범위만을 선별 분석하여 파이프라인 지연을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 오탐 과다로 인한 개발자 경고 피로(Alert Fatigue) | **도메인 특화 룰셋 튜닝 및 False Positive 예외 처리(Suppress)** | 분석 신뢰도 향상 및 핵심 보안 이슈 집중 |
| 대규모 코드베이스 분석 시 CI 파이프라인 지연 | **PR 단위 증분 분석(Incremental Scan) 및 야간 전수 스캔 분리** | 개발 피드백 속도 유지 및 전체 커버리지 확보 |
| 서드파티 라이브러리 오검출로 인한 노이즈 | **외부 라이브러리 폴더 제외(Exclusion) 및 SCA 도구 분리** | 자체 개발 소스코드 보안 약점에 집중 검증 |

#### 한줄 요약

- 룰셋 튜닝, PR 증분 분석, SCA 도구 분리로 분석 정확도와 파이프라인 속도를 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SSDLC(Secure Software Development Life Cycle)**: 소프트웨어 개발 전 주기에 걸쳐 각 단계별 보안 활동(위협 모델링, SAST, DAST)을 통합한 보안 개발 생명주기.

</details>

- **SAST**는 개발 초기에 보안 약점을 원천 차단하는 핵심 수단이며, 룰셋 최적화와 DAST/SCA와의 연계를 통해 완성도 높은 SSDLC를 구축

#### 한줄 요약

- 소스코드 수준의 SAST와 런타임 수준의 DAST를 결합하여 개발 전 주기의 안전성을 보장
