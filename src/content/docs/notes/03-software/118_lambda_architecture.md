## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **람다 아키텍처(Lambda Architecture)**: 전체 데이터를 다시 계산하는 배치 계층과 최신 이벤트를 증분 처리하는 속도 계층의 결과를 결합하는 데이터 처리 구조이다.

</details>

- 정의/개념: 배치와 속도 계층을 결합한 **람다 아키텍처**
- 배경/필요성: 증분 처리만으로는 과거 오류를 반영한 **전체 결과 재생성 불가**

#### 한줄 요약
- 전체 장부와 최신분 임시 장부를 따로 만들고 조회할 때 합친다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **이중 처리**: 같은 업무 계산을 배치 경로와 실시간 경로에서 병행하는 특성이다.
- **불변 원본**: 모든 사건을 덮어쓰지 않고 추가형으로 보존해 전체 결과를 다시 만들 수 있게 하는 데이터이다.
- **결과 결합**: 배치 뷰와 속도 뷰의 포함 시점을 대조해 중복•누락 없이 조회 결과를 만드는 방식이다.

</details>

- **불변 원본**: 전체 결과 재생성 가능
- **이중 처리**: 배치 기준•실시간 증분 병행
- **결과 결합**: 포함 시점으로 중복•누락 통제

#### 한줄 요약
- 최신성을 얻는 대신 같은 계산을 두 경로에서 일치하게 유지해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **처리 위치**: 배치와 속도 뷰에 포함된 이벤트 경계를 나타내는 값이다.
- **뷰 버전**: 배치 결과의 교체 단위와 중복 제거 기준을 나타내는 값이다.
- **배치 계층**: 불변 원본 전체를 다시 계산해 기준 뷰를 생성하는 계층이다.
- **속도 계층**: 새 이벤트를 낮은 지연으로 증분 계산해 최신 뷰를 만드는 계층이다.
- **제공 계층**: 완성된 배치 뷰를 교체하고 아직 포함되지 않은 증분 뷰를 결합하는 조회 계층이다.

</details>

```text
                        [불변 원본]
                         /       \
                  [배치 계층] [속도 계층]
                         \       /
                        [제공 계층]
                             |
                     [처리 위치•버전]
```

선의 의미: 불변 원본 아래에는 전체 기준 뷰와 최신 증분 뷰를 담당하는 배치•속도 계층이 병렬로 놓이고, 제공 계층은 두 뷰와 처리 위치•버전을 결합하는 정적 조회 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 불변 원본 | 모든 사실을 **추가형** 으로 보존 |
| 배치 계층 | **전체 기준 뷰** 재생성 |
| 속도 계층 | 최신 이벤트 **증분 계산** |
| 제공 계층 | **뷰 교체•증분 결합** |
| 처리 위치•버전 | **포함 범위•제거 기준** 관리 |

#### 한줄 요약

- 원본 장부, 전체 계산자, 최신 계산자, 조회 장부, 시간표로 구성된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **최신 증분 뷰 생성**: 속도 계층이 새 이벤트를 계산하는 단계다.
- **불변 원본 누적**: 모든 이벤트를 전체 재계산 입력으로 보존하는 단계다.
- **새 배치 뷰 생성**: 전체 원본에서 기준 결과를 다시 만드는 단계다.
- **배치 포함 시점 갱신**: 새 기준 뷰와 겹친 증분을 제거하는 단계다.

</details>

```text
새 이벤트
    |
    +-- 속도 경로
    |       |
    |       +--> 1. 최신 증분 뷰 생성
    |
    +-- 배치 경로
            |
            +--> 2. 불변 원본 누적
                       |
                       v
                  3. 새 배치 뷰 생성
                       |
                       v
                  4. 배치 포함 시점 갱신
    |
    v
배치 뷰•미포함 증분 결합
    |
    v
조회 결과 반환
```

**동작 원리**

- **1. 최신 증분 뷰 생성**: 최신 이벤트를 낮은 지연으로 계산
- **2. 불변 원본 누적**: 전체 재계산 데이터를 보존
- **3. 새 배치 뷰 생성**: 전체 기준 결과 재생성
- **4. 배치 포함 시점 갱신**: 중복 증분 제거 경계 전달

#### 한줄 요약

- 임시 장부로 최신분을 보여주다가 전체 장부가 완성되면 겹친 임시 기록을 치운다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **Kappa Architecture**: 하나의 스트림 처리 경로에서 실시간 처리와 과거 이벤트 재생을 수행하는 구조이다.

</details>

| 데이터 처리 아키텍처 | Lambda Architecture | Kappa Architecture |
|:---|:---|:---|
| 적용 기준 | **전체 재계산** 중요 | **로그 재생 처리량** 충분 |
| 핵심 특징 | **배치•속도 이중 경로** | **단일 스트림 경로** |
| 한계 | **로직 중복•결과 불일치** | **재생 지연•상태 이관** |

#### 한줄 요약
- 람다는 두 장부를 만들고, 카파는 같은 처리기로 과거 기록까지 다시 읽는다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **공통 명세**: 두 처리 경로가 공유하는 계산 규칙이다.
- **결과 대사**: 동일 구간의 배치•속도 결과를 비교하는 통제이다.
- **이벤트 식별자(Event Identifier)**: 사건을 고유하게 구분하는 키이다.
- **포함 시점**: 배치•속도 뷰의 중복과 누락을 판정하는 시간 경계이다.
- **버전 뷰**: 새 배치 결과를 기존 결과와 분리해 완성하는 저장 단위이다.
- **원자 포인터 전환**: 조회 대상을 새 뷰로 한 번에 바꾸는 배포 방식이다.
- **파티션 조정**: 전체 재처리의 실행 범위를 나누는 통제이다.
- **우선순위 조정**: 실시간 처리 자원을 먼저 배정하는 통제이다.
- **지연 창**: 마감 뒤 도착한 이벤트를 기다리는 시간 범위이다.
- **정정 정책**: 닫힌 결과를 다시 계산하는 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 두 경로의 규칙 변경 시 결과 분기 | **공통 명세•결과 대사** | **구현 차이** 탐지 |
| 배치•속도 뷰의 포함 구간 중첩 | **이벤트 식별자•포함 시점** 관리 | **이중 계산•누락** 방지 |
| 생성 중인 배치 뷰가 조회에 노출 | **버전 뷰•원자 포인터 전환** | **부분 배포** 방지 |
| 전체 원본 재처리로 자원 경합 | **파티션•우선순위 조정** | **처리시간•비용** 통제 |
| 마감 뒤 이벤트로 기준 뷰 불일치 | **지연 창•정정 정책** 정의 | **닫힌 결과 오류** 복구 |

#### 한줄 요약
- 두 장부의 시간 경계를 명시해야 같은 거래를 두 번 더하거나 빠뜨리지 않는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **선택 기준**: 전체 재계산 가치와 이중 로직 유지 비용의 비교 축이다.

</details>

- 전체 재계산 가치가 이중 로직 비용보다 크면 **Lambda**, 아니면 **Kappa** 선택

#### 한줄 요약
- 빠른 임시 답과 정확한 전체 답을 함께 운영할 수 있을 때 쓰는 구조이다.
