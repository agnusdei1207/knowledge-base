## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **람다 아키텍처**: 전체 이력의 정확성을 책임지는 배치 계층(Batch), 최신 데이터의 실시간성을 책임지는 속도 계층(Speed), 두 결과를 통합 서빙하는 계층(Serving)의 3단 구조.
- **Nathan Marz**: 람다 아키텍처를 창안한 엔지니어로, 불변 마스터 데이터셋과 이중 파이프라인 개념을 정립.

</details>

- 정의/개념: 빅데이터 분석에서 **정확성을 보장하는 배치 계층(Batch)과 초저지연을 보장하는 속도 계층(Speed) 및 통합 서빙 계층(Serving)을 결합**하는 데이터 아키텍처
- 배경/필요성: 실시간 스트리밍 단독 처리 시 발생하는 **전체 이력 재계산의 어려움, 과거 데이터 소급 정정 불가 및 분석 정확성 저하 해결 불가**

#### 한줄 요약
- 배치 계층의 완벽한 정확성과 속도 계층의 실시간성을 서빙 계층에서 융합하여 서비스한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Immutable Master Dataset**: 원본 데이터를 절대 수정하지 않고 Append-Only로 영구 보존하여 언제든 배치 전면 재계산(Recomputation)을 보장.
- **Eventual Exactness**: 속도 계층의 임시 계산 오차가 발생하더라도 주기적인 배치 실행을 통해 100% 사후 정정되는 성질.

</details>

- 원천 데이터의 불변(Immutable) 보존 및 **전면 재계산(Re-computation) 보장**
- 속도 계층의 임시 오차를 주기적 배치 계산으로 **100% 사후 정정(Eventually Exact)**
- 배치와 스트리밍의 이중 구축으로 인한 **이중 코드베이스(Code Drift) 관리 부담**

#### 한줄 요약
- 불변 원천 데이터와 이중 연산 계층을 통해 정확성과 실시간성을 동시에 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Batch View & Real-time View**: 배치 계층이 HDFS/Spark로 사전 계산한 불변 뷰와 속도 계층이 Flink/Storm으로 계산한 최신 증분 뷰.

</details>

```text
[람다 아키텍처 3대 계층 구조]
|-- 원천 데이터 수집 (All Ingested Immutable Events: Kafka / S3 Master)
|   |-- Batch Layer (Spark / Hadoop: 전체 이력 대상 일괄 연산 -> Precomputed Batch View)
|   `-- Speed Layer (Flink / Storm: 최근 1시간 미반영 데이터 실시간 연산 -> Real-time View)
`-- Serving Layer (HBase / Cassandra: 클라이언트 쿼리 시 Batch View + Real-time View 병합 서빙)
```

선의 의미: 계층 및 데이터가 배치와 속도 계층으로 분기되어 연산된 후 서빙 계층에서 통합되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **원천 데이터셋 (Master)** | 원시 이벤트를 불변(Immutable) 상태로 보관하여 **언제든 전면 재계산 보장** | Append-Only 영구 저장 |
| **배치 계층 (Batch Layer)**| 대규모 전체 이력 데이터를 주기로 일괄 연산하여 **100% 정확한 Batch View 생성** | Spark/HDFS 기반 고정확성 |
| **속도 계층 (Speed Layer)**| 배치 처리 지연 구간의 최신 스트림 데이터를 **초저지연으로 즉시 계산하여 View 생성** | Flink/Storm 기반 실시간성 |
| **서비스 계층 (Serving)** | 배치 뷰와 실시간 뷰를 색인하고 **클라이언트 쿼리 시 두 결과를 실시간 병합 반환** | HBase/Cassandra 인덱싱 |

#### 한줄 요약
- 원천 데이터, 배치 계층, 속도 계층, 서비스 계층이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Time-Boundary Cutoff**: 서비스 계층에서 배치 뷰의 완료 시점(Timestamp)을 기준으로 겹치는 실시간 스트림 데이터를 중복 제거하는 메커니즘.

</details>

```text
새로운 비즈니스 이벤트 발생 및 수집
        │
   1. [불변 마스터 저장] Kafka를 거쳐 S3/HDFS 불변 로그 스토리지에 Append-Only 기록
        │
   ┌────┴───────────────────────────┐
[배치 계층]                     [속도 계층]
2. Spark가 전체 이력 일괄 집계   3. Flink가 최근 미반영 스트림 즉시 증분 집계
   (완벽한 정확성, 시간 단위 갱신) (초저지연 임시 뷰 생성)
        │                               │
   └────┬───────────────────────────┘
        ▼
   4. [타임스탬프 컷오프] 서비스 계층에서 배치 뷰 완료 시점을 기준으로 중복 구간 제거
        │
   5. 클라이언트 질의에 Batch View + Real-time View를 실시간 병합하여 최신 정확한 결과 반환
```

#### 한줄 요약
- 이벤트 수집 → 배치/속도 병렬 연산 → 타임스탬프 컷오프 → 서빙 계층 병합 반환 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **람다 vs 카파 아키텍처**: 배치와 속도의 이중 파이프라인(람다)과 배치 계층을 제거하고 단일 스트림 엔진으로 통일한 카파(Kappa).

</details>

| 비교 항목 | 람다 아키텍처 (Lambda Architecture) | 카파 아키텍처 (Kappa Architecture) |
|:---|:---|:---|
| 파이프라인 구성 | **이중 파이프라인 (Batch Layer + Speed Layer)**| **단일 스트림 파이프라인 (Stream Processing Only)**|
| 과거 데이터 재처리 | 배치 엔진(Spark)을 통해 전체 이력 재계산 | **Kafka 로그 보존 주기를 늘려 스트림 재생(Replay)**|
| 코드 및 운영 복잡도| **이중 코드베이스 작성 및 동기화 부담 큼** | **단일 코드베이스(Flink)로 운영 복잡도 대폭 감소** |
| 최적 적용 분야 | **금융 결제 대사, 정밀한 100% 무결점 통계** | **실시간 추천, 사용자 행동 분석, IoT 관제** |

#### 한줄 요약
- 이중 계층으로 정확성을 보장하는 람다와 단일 스트림 엔진으로 운영을 단순화한 카파를 비교한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Code Drift**: 배치 로직과 스트림 로직을 서로 다른 언어나 프레임워크로 구현하여 비즈니스 계산 결과가 미세하게 어긋나는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 배치와 스트림 로직 불일치로 인한 결과 왜곡 (**Code Drift**) | **Apache Beam 또는 Apache Flink 기반 단일 API 로직 공통화** | 이중 개발 방지 및 로직 일관성 보장 |
| 서비스 계층에서 배치 뷰와 실시간 뷰의 중복 합산 | **엄격한 워터마크(Watermark) 및 타임스탬프 컷오프 알고리즘 적용** | 데이터 중복 연산 원천 차단 |
| 하둡 클러스터와 스트리밍 클러스터의 이중 인프라 운영 비용 | **현대적 카파 아키텍처 또는 레이크하우스 스트리밍 엔진으로 전환** | 인프라 운영 복잡도 50% 절감 |
| 서빙 계층 질의 시 다중 DB 룩업 지연 | **인메모리 캐시(Redis) 계층 전면 배치 및 병렬 서브쿼리 실행** | 사용자 체감 응답 속도 최적화 |

#### 한줄 요약
- 단일 API 공통화, 워터마크 컷오프, 레이크하우스 전환, 서빙 캐시로 람다의 한계를 보완한다.

## Ⅶ. 결론

- 빅데이터 분석에서 실시간성과 완벽한 정합성을 동시에 확보하기 위해 **람다 아키텍처의 배치-속도-서빙 분리 사상을 적재적소에 채택**하고, **Apache Beam 기반 코드 단일화와 Iceberg 레이크하우스 기술을 융합**하여 차세대 분석 플랫폼 구축

#### 한줄 요약
- 람다 아키텍처는 배치 계층과 속도 계층의 결합을 통해 빅데이터 분석의 정확성과 실시간성을 조화시킨 기념비적인 데이터 아키텍처다.
