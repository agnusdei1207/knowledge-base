## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **멀티레벨 피드백 큐(Multilevel Feedback Queue, MLFQ)**: CPU 사용 이력에 따라 프로세스를 우선순위 큐 사이에서 이동시키는 선점 스케줄링 기법이다.

</details>

- 정의/개념: **MLFQ**는 CPU 사용 이력에 따라 큐를 이동시켜 우선순위를 조정하는 선점 스케줄링 정책이다.
- 배경/필요성: 작업 길이를 모르면 고정 우선순위로 응답성과 **기아**를 동시에 통제할 수 없다.

#### 한줄 요약

- CPU 사용 이력으로 작업 우선순위 큐를 동적으로 조정한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **강등(Demotion)**: CPU를 오래 쓴 작업을 하위 큐로 내리는 정책이다.
- **우선순위 상향(Priority Boost)**: 오래 기다린 작업을 상위 큐로 올리는 정책이다.
- **기아(Starvation)**: 낮은 우선순위 작업이 실행 기회를 계속 얻지 못하는 상태이다.
- **대화형 작업(Interactive Job)**: 짧은 CPU 실행과 입력 대기를 반복하는 부하 유형이다.
- **CPU 집중 작업(CPU-bound Job)**: CPU 연산을 오래 이어가는 부하 유형이다.

</details>

- 실행 이력으로 **대화형 작업**과 **CPU 집중 작업**을 구분한다.
- 할당량을 소진하면 **강등**하여 CPU 독점을 제한한다.
- 주기적인 **우선순위 상향**으로 하위 큐의 **기아**를 방지한다.

#### 한줄 요약

- 버스트를 사전에 예측하지 않고 대화형•CPU 집중 작업을 분리한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **우선순위 큐 계층**: 서로 다른 시간 할당량과 우선순위를 가진 여러 준비 큐의 구조이다.
- **피드백 규칙(Feedback Rule)**: CPU 사용 이력과 상향 주기에 따라 작업이 머물 큐를 결정하는 규칙이다.
- **우선순위 선택기(Priority Selector)**: 비어 있지 않은 최상위 큐에서 실행 작업을 고르는 구성이다.
- **상향 타이머(Boost Timer)**: 최대 대기시간에 맞춰 우선순위 상향 시점을 통지하는 구성이다.

</details>

```text
[우선순위 큐 계층]
          |
[우선순위 선택기]
          |
    [피드백 규칙] -- [상향 타이머]
```

선의 의미: 큐 계층과 선택기의 선은 최상위 실행 후보 제공 관계, 선택기와 피드백 규칙의 선은 실행 이력에 따른 큐 소속 조정 관계, 피드백 규칙과 상향 타이머의 선은 기아 방지를 위한 주기적 상향 조건 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 우선순위 큐 계층 | 작업•할당량 보관 |
| 우선순위 선택기 | 최상위 작업 선택 |
| 피드백 규칙 | 유지•강등•상향 결정 |
| 상향 타이머 | 기아 방지 시점 통지 |

#### 한줄 요약

- **우선순위 큐 계층**, **피드백 규칙**, **상향 타이머**의 피드백 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **시간 할당량(Time Quantum)**: 한 차례 CPU를 연속 사용할 수 있는 시간이다.
- **CPU 사용 이력**: 작업의 할당량 소진 여부와 실제 CPU 사용시간을 기록한 정보이다.
- **최대 대기시간(Maximum Waiting Time)**: 낮은 우선순위 작업이 실행 없이 기다릴 수 있는 상한이다.
- **최상위 비어 있지 않은 큐 선택**: 실행 후보가 있는 가장 높은 우선순위 큐를 고르는 단계이다.
- **큐별 시간 할당량 실행**: 선택한 큐의 시간 할당량만큼 작업을 실행하는 단계이다.
- **CPU 사용 이력 판정**: 조기 대기와 할당량 소진 여부를 구분하는 단계이다.
- **하위 큐 강등**: 할당량을 소진한 CPU 집중 작업을 낮은 큐로 옮기는 단계이다.

</details>

```text
[신규 작업을 최상위 큐에 등록]
              │
              ▼
┌──────────── MLFQ 실행 반복 ────────────┐
│ 1. 최상위 비어 있지 않은 큐 선택       │
│              │                         │
│              ▼                         │
│ 2. 큐별 시간 할당량 실행               │
│              │                         │
│              ▼                         │
│ 3. CPU 사용 이력 판정                  │
│       ┌──────┴─────────┐               │
│       │ 조기 대기      │ 할당량 소진   │
│       ▼                ▼               │
│ [현재 큐 유지]   4. 하위 큐 강등       │
│       └────────┬───────┘               │
│                │ 상향 주기 도달        │
│                ▼                       │
│         5. 우선순위 상향               │
│                └── 큐 선택으로 반복    │
└────────────────────────────────────────┘
```

### 동작 원리

1. **최상위 비어 있지 않은 큐 선택**: 최고 우선순위 후보를 결정한다.
2. **큐별 시간 할당량 실행**: 우선순위별 CPU 사용 범위를 적용한다.
3. **CPU 사용 이력 판정**: 조기 대기와 할당량 소진을 구분한다.
4. **하위 큐 강등**: CPU 집중 작업의 독점을 제한한다.
5. **우선순위 상향**: 최대 대기시간 전에 하위 작업을 승격한다.

#### 한줄 요약

- **CPU 사용 이력 판정** 뒤 할당량을 소진하면 **하위 큐 강등**, **최대 대기시간**에 이르면 **우선순위 상향**을 수행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **멀티레벨 큐(Multilevel Queue, MLQ)**: 프로세스를 고정 우선순위 큐에 분류하고 큐 사이를 이동시키지 않는 기법이다.
- **혼합 부하**: 대화형 작업과 CPU 중심 작업이 함께 실행되는 작업 구성이다.

</details>

| 스케줄링 정책 | MLFQ | 멀티레벨 큐(MLQ) |
|:---|:---|:---|
| 적용 기준 | 작업 길이 미상•**혼합 부하** | 작업 유형별 우선순위 고정 |
| 핵심 특징 | CPU 사용 이력의 큐 이동 | 프로세스의 소속 큐 고정 |
| 한계 | 할당량•상향 주기 설정 복잡성 | 낮은 큐의 **기아** 가능성 |

> 요약: 작업 길이가 변하면 **MLFQ**, 유형별 우선순위가 고정되면 **MLQ**를 선택한다.

#### 한줄 요약

- 실행 이력이 변하면 MLFQ, 유형이 고정되면 MLQ가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **CPU 사용량 회계(CPU Usage Accounting)**: 작업이 실제 사용한 CPU 시간을 누적해 우선순위 정책에 반영하는 처리이다.
- **기하급수 할당량(Geometric Quantum)**: 하위 큐로 갈수록 일정 배수로 길어지는 시간 할당량이다.
- **꼬리 응답시간(Tail Response Time)**: 응답시간 분포의 상위 백분위에 해당하는 느린 작업 시간이다.
- **스케줄링 오버헤드**: 큐 관리와 문맥 전환처럼 실제 작업 실행 외에 CPU를 소비하는 관리 비용이다.
- **분산 상향(Staggered Boost)**: 작업별 승격 시점을 분산하는 정책이다.
- **상향 예산(Boost Budget)**: 한 번에 승격할 작업 수를 제한하는 정책이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 상위 큐가 계속 차서 하위 큐 작업에 **기아** 발생 | **최대 대기시간** 기반 **우선순위 상향** | 배치 작업 진행 보장 |
| 짧은 입출력 대기로 CPU 중심 작업이 상위 큐 유지 | 누적 사용시간 기반 **CPU 사용량 회계** | 우선순위 조작 방지 |
| 큐•할당량 세분화로 문맥 전환 증가 | 최소 큐 수와 **기하급수 할당량** 설정 | **스케줄링 오버헤드** 감소 |
| 전역 상향 순간에 상위 큐가 몰려 **꼬리 응답시간** 악화 | **분산 상향**과 **상향 예산** 적용 | 상위 큐 혼잡 완화 |

#### 한줄 요약

- I/O 대기형 작업은 짧은 CPU 버스트로 상위 큐를 유지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **상향 주기**: 기아 방지를 위해 하위 큐 작업을 상위 큐로 올리는 시간 간격이다.
- **MLFQ 조정 기준**: 꼬리 응답시간과 최대 대기시간을 비교해 큐별 할당량과 상향 주기를 정하는 기준이다.

</details>

- **MLFQ 조정 기준**에 따라 꼬리 응답이 목표를 넘으면 상위 큐 할당량을 줄이고, 최대 대기가 넘으면 **상향 주기**를 줄인다.

#### 한줄 요약

- **꼬리 응답시간**과 **최대 대기시간**으로 할당량•상향 주기를 조정한다.
