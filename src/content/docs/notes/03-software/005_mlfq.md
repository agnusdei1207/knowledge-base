## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다단계 피드백 큐(Multilevel Feedback Queue, MLFQ)**: 누가 얼마나 길게 일할지 알 수 없는 상황에서, 주어진 시간을 다 쓴 놈은 계급을 깎고 양보한 놈은 유지시켜서 자율적으로 큐 서열을 통제하는 스케줄링이다.
- **우선순위 부스트(Priority Boost)**: 밑바닥 계급에 갇혀서 CPU 구경도 못 하고 굶어 죽어가는 놈들을 살리려고, 정해진 시간마다 무조건 최상위 큐로 멱살 잡고 끌어올리는 주기적 대사면이다.
- **게임 디펜스(Gaming Defense)**: 프로세스가 계급 안 깎이려고 시간 다 되기 직전에 꼼수로 반납하는 얌체 짓을 막으려고, 이번 큐에서 쓴 시간을 누적해서 기어코 깎아버리는 방어막이다.

</details>

- 정의: 프로세스의 실행 동작 이력(I/O-bound vs CPU-bound)에 따라 우선순위 레벨을 자율 피드백 조율하는 실무 스케줄링 정책인 **다단계 피드백 큐(MLFQ)**
- 배경: 각 프로세스가 CPU를 얼마나 오래 쓸지 미리 알 수 없어서, SJF처럼 이상적인 우선순위를 사전에 박아둘 수 없기 때문

#### 한줄 요약

- CPU 오래 쓰면 밑으로 강등시키고, 굶어 죽을 때쯤 다 같이 올려서 공평하게 돌리는 눈치코치 알고리즘이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **강등(Demotion)**: 정해진 시간(타임 슬라이스)을 혼자 다 긁어 쓴 이기적인 프로세스의 우선순위를 한 단계 밑바닥 큐로 무자비하게 쫓아내는 철권통치이다.
- **대화형 작업 우대(Interactive Job Prioritization)**: 사용자가 키보드나 마우스를 눌렀을 때 0.1초 만에 반응해야 하는 프로세스를 상위 큐에 고정시켜서 쾌적한 반응성을 사수하는 꼼수이다.

</details>

- 시간 할당량이 다른 여러 개의 큐 계층(Q0 > Q1 > Q2)을 피라미드처럼 쌓아둠.
- 새로 들어온 놈은 일단 최고 계급(Q0)에 꽂아주고, 시간 다 쓰면 얄짤없이 하위 큐로 **강등(Demotion)**시켜버림.
- 주기적인 **우선순위 부스트**로 기아를 막고 누적 시간 계산으로 스케줄러를 농락하는 꼼수를 100% 차단함.

#### 한줄 요약

- 시간 많이 쓰면 강등, 양보하면 유지, 오래 기다리면 부스트 상향으로 밸런스를 맞춘다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **타임 슬라이스 확장(Time Slice Scaling)**: 밑바닥 큐로 떨어질수록 "넌 어차피 오래 걸리는 놈이니까 교대라도 줄이자"며 할당 시간을 2배씩 팍팍 늘려주는 설계이다.

</details>

```text
[ 다단계 피드백 큐(MLFQ) 십자포화 아키텍처 ]
         [ 우선순위 큐 계층 ]
[ Q0 (최고 계급 / 짧은 몫) ] ◄── (부스트 상향) ──┐
         │ (강등)                             │
         ▼                                    │
[ Q1 (중간 계급 / 중간 몫) ]                    │
         │ (강등)                             │
         ▼                                    │
[ Q2 (밑바닥 / 긴 몫) ]                       │
         │                                    │
┌────────┴────────┐                           │
│ 우선순위 선택기 │ ── (피드백 규칙) ── [ 상향 타이머 ]
└────────┬────────┘
         ▼
    [ CPU (실행) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **우선순위 큐 계층** | 짧은 몫의 최고 계급(Q0)부터 긴 몫의 밑바닥(Q2)까지 차등화된 피라미드 대기실 |
| 우선순위 선택기 | 비어 있지 않은 제일 높은 큐의 1빠따 프로세스를 멱살 잡고 CPU에 꽂아주는 실무자 |
| 피드백 규칙 | 타임 슬라이스 다 쓰면 얄짤없이 **강등(Demotion)**시키고, 얌전히 양보하면 유지시키는 룰 |
| 상향 타이머 | 정해진 주기(S)마다 무자비하게 알람을 터트려 전원을 최상위 Q0로 쏘아 올리는 기폭제 |

#### 한줄 요약

- 큐가 여러 층으로 나뉘고, 몫을 쓴 놈은 아래로 밀리며, 타이머가 울리면 다 같이 맨 위로 올라간다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **MLFQ 5대 규칙(Rules of MLFQ)**: 1) 계급 높으면 실행 2) 같으면 RR 3) 신규는 최고 계급 4) 할당량 채우면 강등 5) 주기마다 전원 최고 계급 상향이라는 절대 불변의 철칙 5가지이다.

</details>

```text
[ MLFQ 5대 규칙 기반 동적 상태 피드백 흐름 ]
[ 1. 신규 작업을 최상위 큐(Q0)에 냅다 꽂음 ]
              │
              ▼
┌──────── MLFQ 실행 반복 ────────┐
│ 2. 최상위 비어 있지 않은 큐 선택 │
│              │                 │
│              ▼                 │
│ 3. 큐별 시간 할당량(RR) 실행   │
│              │                 │
│              ▼                 │
│ 4. CPU 사용 이력 판정          │
│       ┌──────┴──────┐          │
│ (조기 양보)  (할당량 100% 소진)│
│       ▼             ▼          │
│ [현재 큐 유지]  5. 하위 큐 강등│
│       └──────┬──────┘          │
│              │ (주기 도달 시)  │
│              ▼                 │
│       6. 우선순위 부스트 상향  │
│              └── 반복 ─────────┘
└────────────────────────────────┘
```

### 동작 원리

1. 신규 등록: 들어오자마자 일단 최고 우선순위 큐(Q0)에 꽂아서 기회를 줌.
2. 최상위 큐 선택: 빈 큐는 거르고 제일 높은 계급에 있는 놈부터 뽑음.
3. 시간 할당량 실행: 그 큐에 정해진 시간(타임 슬라이스)만큼 실행시킴.
4. 강등(Demotion): 시간 다 쓸 때까지 안 나오면 다음 타임을 위해 하위 큐로 냅다 **강등**시킴.
5. 우선순위 부스트 상향: 일정 시간이 지나면 밑바닥에 깔린 놈들까지 전부 최상위 큐로 **부스트** 상향시켜서 기아를 면하게 함.

#### 한줄 요약

- 위에 꽂아주고, 시간 다 쓰면 한 칸 내리고, 정해진 시간 되면 다 같이 올려서 다시 시작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다단계 큐(Multilevel Queue, MLQ)**: 태어날 때부터 넌 시스템 큐, 넌 유저 큐로 계급을 박아버리고 죽을 때까지 못 바꾸게 하는 꽉 막힌 철밥통 스케줄러이다.

</details>

| 비교 항목 | **MLFQ** (Multilevel Feedback Queue) | **MLQ** (Multilevel Queue) |
|:---|:---|:---|
| 큐 간 이동 유무 | 실행 이력에 따라 위아래로 동적 이동 가능 (**강등 & 우선순위 부스트**) | 한 번 박히면 이동 불가 (정적 고정 큐 배치) |
| 프로세스 정보 요구 | 사전에 실행 시간 따위 몰라도 눈치껏 다 학습함 | 태어날 때 이게 무슨 타입인지 꼬리표를 달아줘야 함 |
| 유연성 및 기아 대응 | **우선순위 부스트**로 밑바닥 놈들을 다 구출해 냄 | 하위 큐에 박힌 놈들은 평생 굶어 죽을(기아) 위험이 넘침 |

#### 한줄 요약

- MLFQ는 눈치껏 계급을 바꾸며 적응하고, MLQ는 한 번 박힌 계급으로 굶어 죽어도 안 바꾼다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스케줄러 농락(Gaming the Scheduler)**: 꼼수 프로세스가 강등 안 당하려고 99% 썼을 때 의도적으로 I/O를 터트려 양보하는 척하며 큐를 지키는 악질 해킹 수법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 밑바닥 큐에 처박힌 묵직한 연산 작업들이 평생 CPU를 못 잡고 굶어 죽음(기아) | 일정 주기마다 전원을 최고 계급으로 끌어올리는 **우선순위 부스트** 멱살 시전 | 영양실조 걸린 프로세스들을 구출하고 최대 대기시간 리밋 방어 |
| 꼼수 프로세스가 99%만 쓰고 반납해서 강등을 피하는 **스케줄러 농락** 발생 | 양보할 때마다 타이머를 리셋 안 하고 **누적 사용량**을 깐깐하게 합산해 깎아버림 | 눈속임으로 꼼수 부리는 이기적인 프로세스의 상위 큐 알박기 원천 차단 |
| 하위 큐에서도 할당 시간이 짧으면 밑도 끝도 없는 문맥 전환으로 시스템이 질식함 | 밑으로 떨어질수록 **시간 할당량 크기를 2배씩 늘려줘서** 진득하게 일하게 만듦 | 쓸데없는 교대 비용 낭비를 줄이고 무거운 계산 처리량 극대화 |

#### 한줄 요약

- 기아는 부스트로 깨우고, 꼼수는 누적량 계산으로 잡아내며, 무거운 작업은 시간 할당량을 팍팍 늘려준다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **MLFQ 파라미터 튜닝 기준(MLFQ Tuning Criteria)**: 큐를 몇 개나 깔지, 계급마다 시간을 얼마나 줄지, 부스트 주기를 얼마로 잡을지 정해서 시스템 성능을 멱살 잡고 캐리하는 설계 잣대이다.

</details>

- **MLFQ 파라미터 튜닝 기준** 원칙에 따라, CPU 버스트를 전혀 모르는 혼합 환경은 **MLFQ**를, 작업 성격이 태어날 때부터 고정된 환경은 **MLQ** 채택 기조 확립함

#### 한줄 요약

- 작업 유형을 짐작조차 할 수 없을 땐 눈치껏 계급을 조절하는 MLFQ가 정답이다.
