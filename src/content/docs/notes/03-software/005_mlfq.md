## 미리 알고가기

- **멀티레벨 피드백 큐(Multilevel Feedback Queue, MLFQ, 엠엘에프큐)**: 영문 각 단어의 첫 글자를 따 MLFQ로 표기하며 CPU 사용 이력으로 우선순위를 바꾸는 스케줄링 기법
- **멀티레벨 큐(Multilevel Queue, MLQ, 엠엘큐)**: 영문 각 단어의 첫 글자를 따 MLQ로 표기하며 프로세스를 고정 우선순위 큐에 분류하는 스케줄링 기법
- **중앙처리장치(Central Processing Unit, CPU, 시피유)**: 영문 각 단어의 첫 글자를 따 CPU로 표기하며 프로세스 명령을 실행하는 연산 장치
- **준비 큐(Ready Queue)**: CPU 실행을 기다리는 프로세스 대기열
- **CPU 버스트(CPU Burst)**: 프로세스가 CPU를 연속 사용하는 구간
- **시간 할당량(Time Quantum)**: 한 차례 CPU를 연속 사용할 수 있는 시간
- **라운드 로빈(Round Robin)**: 같은 큐의 작업에 CPU 시간을 차례로 배분
- **강등**: 프로세스를 한 단계 낮은 큐로 이동
- **우선순위 상향**: 모든 프로세스를 최상위 큐로 이동
- **기아(Starvation)**: 낮은 우선순위 작업이 실행 기회를 계속 얻지 못하는 상태
- **선점 스케줄링(Preemptive Scheduling)**: 할당량 만료나 높은 우선순위 작업 도착 시 실행 중인 프로세스의 CPU를 회수하는 정책
- **스케줄러(Scheduler)**: 준비 큐의 우선순위와 피드백 규칙을 적용해 다음 실행 프로세스를 선택하는 운영체제 구성요소
- **피드백 규칙(Feedback Rule)**: 실제 CPU 사용 이력과 상향 주기에 따라 프로세스가 머물 큐를 결정하는 규칙
- **대화형 셸(Interactive Shell)**: 키 입력과 명령 결과를 주고받아 짧은 CPU 버스트와 대기가 반복되므로 상위 큐에 남기 쉬운 명령 인터페이스
- **빌드 프로세스(Build Process)**: 소스 코드를 컴파일·링크하며 긴 CPU 버스트를 사용하는 작업으로서 할당량을 소진하면 하위 큐로 강등된다.
- **최대 대기시간(Maximum Waiting Time)**: 낮은 우선순위 프로세스가 실행 없이 기다릴 수 있는 상한으로서 상향 주기를 정하는 기준

## Ⅰ. 개요

- **정의/개념**: CPU 이력으로 우선순위를 바꾸는 정책
- **배경/필요성**: 작업 길이를 몰라 동적 우선순위 필요

### 쉽게 이해하기 (학습용)

- CPU를 짧게 쓰는 일은 앞줄에, 오래 쓰는 일은 뒷줄에 보내는 줄 세우기다

## Ⅱ. 특징

- 실행 이력으로 작업 길이를 동적으로 추정한다
- 짧은 CPU 버스트는 상위 큐 응답을 얻는다
- 할당량 소진 작업은 강등돼 독점을 막는다
- 주기적 상향은 하위 큐 기아를 방지한다

### 쉽게 이해하기 (학습용)

- 미리 작업 시간을 몰라도 실제로 짧게 쓰는 일을 앞줄에 둘 수 있다

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    subgraph M[MLFQ 스케줄러 경계]
        Q[우선순위 큐 계층]
        S[최고 우선순위 선택기]
        F[피드백 규칙]
        Q -->|비어 있지 않은 최상위 큐| S
        S -->|선택 작업의 실행 이력| F
        F -->|유지·강등·상향| Q
    end
```

| 설계 요소 | 설명 |
|:---|:---|
| 우선순위 큐 계층 | 상위 큐는 짧고 하위 큐는 긴 할당량 |
| 최고 우선순위 선택기 | 큐 간 우선순위·큐 내 라운드 로빈으로 선택 |
| 피드백 규칙 | 할당량 소진·상향 주기로 큐 위치 결정 |

> 요약: 선택기는 실행 순서, 피드백은 큐 위치 결정

### 쉽게 이해하기 (학습용)

- 여러 줄 중 가장 앞선 줄부터 처리하고, 사용 기록에 따라 작업을 다른 줄로 옮긴다

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant P as 프로세스
    participant M as MLFQ 스케줄러
    P->>M: 신규 프로세스 도착
    loop 작업 선택 반복
        M->>P: 최상위 큐 작업 실행
        M->>M: 큐 위치 갱신
        opt 상향 주기 도달
            M->>M: 우선순위 상향
        end
    end
```

| 절차 | 설명 |
|:---|:---|
| 신규 프로세스 도착 | 최상위 큐에 삽입 |
| 최상위 큐 작업 실행 | 비어 있지 않은 최상위 큐에서 선택해 실행 |
| 큐 위치 갱신 | 미완료 작업은 할당량 소진 시 강등, 미소진 시 유지 |
| 우선순위 상향 | 주기마다 모든 작업을 최상위 큐로 이동 |

> 요약: CPU 사용량·상향 주기로 큐 위치 반복 갱신

### 쉽게 이해하기 (학습용)

- 새 작업은 앞줄에서 시작해 CPU를 오래 쓰면 내려가고, 오래 기다리면 다시 올라간다

## Ⅴ. 종류 및 비교

| 판단 기준 | MLFQ | 멀티레벨 큐(MLQ) |
|:---|:---|:---|
| 핵심 특징 | CPU 사용 이력으로 큐 이동 | 프로세스의 소속 큐 고정 |
| 적용 기준 | 작업 길이 미상·대화형 작업 혼재 | 작업 유형별 우선순위 고정 |
| 주요 위험 | 규칙 복잡성·할당량·상향 주기 부적합 | 낮은 큐의 기아 가능성 |

> 요약: 작업 길이 미상은 MLFQ, 작업 유형 고정은 MLQ

### 쉽게 이해하기 (학습용)

- 작업 성격이 바뀌면 사용 기록으로 줄을 옮기고, 유형이 고정되면 정해진 줄을 유지한다

## Ⅵ. 실무 사례

1. 대화형 셸은 짧은 CPU 버스트로 상위 큐 유지
2. 빌드 프로세스는 할당량 소진 시 하위 큐로 강등

### 쉽게 이해하기 (학습용)

- 키 입력을 자주 기다리는 셸은 CPU를 짧게 써서 앞줄에 남는다
- 계속 계산하는 빌드는 자기 몫을 다 쓰므로 뒷줄로 내려간다

## Ⅶ. 결론

- 응답 목표·최대 대기시간으로 할당량·상향 주기 설정

### 쉽게 이해하기 (학습용)

- 화면 반응과 오래 기다리는 작업을 함께 살펴 줄별 사용 시간과 끌어올리는 간격을 정한다
