## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **강등 및 부스트(Demotion & Boost)**: 할당된 타임 퀀텀을 모두 소진한 CPU 집약 작업을 하위 큐로 내리고, 일정 주기마다 모든 작업을 최상위 큐로 올려주는 스케줄링 규칙.
- **응답성 저하 및 기아(Latency & Starvation)**: I/O 대화형 작업이 긴 연산 작업 뒤에 갇혀 반응이 느려지거나 하위 큐의 작업이 영구히 실행되지 못하는 문제.

</details>

- 정의/개념: 작업의 CPU 버스트 이력을 피드백하여 **타임 슬라이스 소진 시 강등(Demotion) 및 부스트(Boost)** 로 큐 계층을 동적 조정하는 적응형 스케줄링 기법
- 배경/필요성: 프로세스 실행 시간 사전 예측의 한계 극복 및 대화형 응답성 확보와 저우선순위 기아 현상 방지 필요

#### 한줄 요약

- 실행 이력으로 CPU 집약 작업은 하위 큐로 강등하고 I/O 집약 작업은 상위 큐에 유지하는 적응형 스케줄러

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **강등(Demotion)**: 타임 슬라이스를 소진한 CPU 집약 프로세스를 한 단계 낮은 우선순위 큐로 이동시키는 처벌 규칙.
- **대화형 작업 우대(Interactive Job Prioritization)**: I/O 대기 후 복귀하는 대화형 프로세스를 높은 우선순위 큐에 유지하여 빠른 응답성을 보장하는 규칙.

</details>

- 타임 슬라이스 초과 시 **강등(Demotion)** 으로 CPU 집약 작업을 하위 큐로 분류
- I/O 완료 후 복귀 프로세스는 현재 큐 수준 유지하는 **대화형 작업 우대** 기반 응답성 확보
- 주기적 **우선순위 부스트** 및 큐 내 누적 시간 기반 **게임 방어** 기반 공정성 유지

#### 한줄 요약

- CPU를 오래 쓰면 하위 큐로 강등하고 I/O 이후 복귀는 상위 유지하여 워크로드를 자동 분류

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **타임 슬라이스 계층(Time Quantum Hierarchy)**: 상위 큐일수록 짧은 타임 슬라이스·높은 우선순위, 하위 큐일수록 긴 타임 슬라이스·낮은 우선순위를 부여하는 큐 계층 설계.

</details>

```text
[ MLFQ 큐 계층 구조 ]
Q0 (최상위, 타임 슬라이스 최단)  ← 신규 진입·I/O 복귀
├─ 타임 슬라이스 초과 → 강등
Q1 (중간, 타임 슬라이스 중간)
├─ 타임 슬라이스 초과 → 강등
Q2 (최하위, 타임 슬라이스 최장)  ← CPU 집약 작업 수렴
우선순위 부스트 (주기 T): Q0으로 전체 이동
```

선의 의미: 가지(`├─`)는 타임 슬라이스 초과 시 하위 큐로의 강등 방향, 우선순위 부스트는 최상위로의 주기적 복귀

| 구성요소 | 책임 |
|:---|:---|
| 다단계 큐 | **타임 슬라이스 계층** 기반 우선순위별 프로세스 분류 |
| 강등 규칙 | 누적 실행 시간 초과 시 **강등** 기반 CPU 집약 작업 하향 |
| 우선순위 부스트 | 주기 T마다 전체 프로세스를 Q0으로 이동하여 **기아 현상** 방지 |
| 게임 방어 | 큐 내 누적 시간 추적으로 자발적 반납의 **강등 회피** 차단 |

#### 한줄 요약

- 다단계 큐와 강등 규칙이 워크로드를 자동 분류하고, 우선순위 부스트가 기아를 방지

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **I/O 집약 작업(I/O-bound Job)**: CPU 연산보다 I/O 대기 시간이 긴 작업으로, 짧은 CPU 버스트 후 I/O 대기를 반복하는 대화형 프로세스.
- **CPU 집약 작업(CPU-bound Job)**: I/O 없이 CPU를 연속으로 오래 사용하는 배치형 연산 프로세스.

</details>

```text
신규 프로세스 도착
   │
   ▼
1. Q0 배치 (최고 우선순위)
   │
   ├─ 타임 슬라이스 내 I/O 발생: 현재 큐 수준 유지 (I/O 복귀 후 복귀)
   └─ 타임 슬라이스 소진
         │
         ▼
      2. 강등: 현재 큐 → 하위 큐 이동
         │
         └─ 최하위 큐 도달 시: FCFS 방식 실행
주기 T마다:
   └─ 3. 우선순위 부스트: 모든 프로세스 → Q0 복귀
```

**동작 원리** 1. **Q0 배치**: 신규 프로세스는 최고 우선순위 Q0에 배치하여 대화형 가능성 우선 처리
2. **강등**: 타임 슬라이스 소진(누적) 시 다음 하위 큐로 강등하여 CPU 집약 작업으로 분류
3. **우선순위 부스트**: 주기 T마다 모든 프로세스를 Q0으로 이동하여 장기 대기 프로세스의 **기아 현상** 방지

#### 한줄 요약

- 신규 진입은 Q0, 타임 슬라이스 소진 시 강등, 주기 부스트로 기아를 방지하는 3단계 흐름

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다단계 큐(Multilevel Queue, MLQ)**: 큐 계층을 고정하여 프로세스 유형을 사전에 분류하는 방식으로, MLFQ처럼 큐 간 이동이 없는 정적 스케줄러.

</details>

| 구분 | MLFQ | MLQ(정적 다단계 큐) |
|:---|:---|:---|
| 적용 기준 | 실행 전 프로세스 유형 미분류·혼합 워크로드 환경 | 프로세스 유형(시스템·사용자·배치)이 사전에 명확히 분류된 환경 |
| 핵심 특징 | **실행 이력** 기반 동적 큐 이동 및 **우선순위 부스트** | 큐 계층 고정, 큐 간 이동 없음 |
| 한계 | 부스트 주기·큐 수 파라미터 튜닝 복잡성 | 프로세스 유형 오분류 시 **기아 현상** 발생 |

#### 한줄 요약

- 실행 전 유형 미분류 혼합 환경은 MLFQ, 사전 분류된 고정 워크로드는 MLQ 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **워크로드 편향(Workload Skew)**: 특정 큐 계층에 프로세스가 집중되어 해당 큐의 대기시간이 급증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하위 큐 장기 대기 프로세스의 **기아 현상** 발생 | 주기 T를 단축하는 **우선순위 부스트** 적용 | 장기 대기 프로세스의 CPU 할당 보장 |
| 자발적 반납으로 강등을 회피하는 **게임 방어** 우회 | 큐 내 누적 CPU 사용 시간 기반 강등 판정 | **게임 방어** 우회 차단 및 공정성 확보 |
| 큐 계층 수·부스트 주기 설정 미흡으로 **워크로드 편향** 발생 | 시스템 응답 목표 및 워크로드 프로파일 기반 파라미터 튜닝 | 큐 계층별 대기시간 균형 확보 |

#### 한줄 요약

- 기아는 부스트 주기 단축으로, 게임 방어 우회는 누적 시간 기반 강등으로, 편향은 파라미터 튜닝으로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **MLFQ 적용 판단 기준**: I/O·CPU 혼합 워크로드에서 실행 이력 기반 자동 분류가 필요하고 기아 방지가 요구될 때 MLFQ를 선택하는 기준.

</details>

- 혼합 워크로드의 자동 분류와 **기아 현상** 방지가 모두 필요한 범용 OS 환경에 **MLFQ** 선택

#### 한줄 요약

- I/O·CPU 혼합 환경에서 실행 이력으로 자동 분류하고 주기 부스트로 기아를 방지할 때 MLFQ를 적용
