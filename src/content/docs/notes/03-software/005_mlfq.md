## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MLFQ(Multilevel Feedback Queue)**: 작업의 CPU 사용 패턴을 학습하여 I/O 바운드 작업은 상위 큐로, CPU 바운드 작업은 하위 큐로 자동 분류하는 적응형 스케줄링.
- **우선순위 부스트(Priority Boost)**: 일정 주기 $S$마다 모든 프로세스를 최상위 큐로 일괄 승격시켜 기아 현상을 원천 방지하는 기제.

</details>

- 정의/개념: 실행 이력을 피드백하여 **타임 퀀텀 소진 시 강등(Demotion) 및 주기적 부스트(Priority Boost)** 를 수행하는 적응형 스케줄링
- 배경/필요성: 작업 실행 시간을 사전 예측할 수 없어 **대화형 작업의 응답성 확보와 CPU 집약 작업의 기아 방지 동시 만족 불가**

#### 한줄 요약
- I/O 바운드 작업은 상위 큐에서 빠른 응답을, CPU 바운드 작업은 하위 큐에서 긴 타임 슬라이스를 부여한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **강등(Demotion)**: 현재 큐에서 할당된 타임 퀀텀을 모두 소진한 프로세스를 한 단계 낮은 우선순위 큐로 강등시키는 규칙.
- **게임 방어(Gaming Defense)**: 프로세스가 타임 퀀텀 만료 직전 의도적으로 짧은 I/O를 발생시켜 상위 큐를 독점하는 어뷰징을 차단하는 기법.

</details>

- 짧은 I/O 바운드 프로세스를 최상위 큐에 유지하여 **대화형 응답성(Response Time)** 극대화
- 타임 슬라이스 소진 시 하위 큐로 **강등(Demotion)** 시켜 CPU 집약 작업의 선점 남용 방지
- 주기적 **우선순위 부스트(Priority Boost)** 및 누적 시간 계측을 통한 **게임 방어** 달성

#### 한줄 요약
- 작업 패턴에 따라 큐를 동적으로 이동시키고 주기적 부스트로 기아를 방지한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **타임 퀀텀 계층(Time Quantum Hierarchy)**: 상위 큐일수록 짧은 타임 퀀텀(10ms)과 높은 우선순위, 하위 큐일수록 긴 타임 퀀텀(80ms)을 부여하는 계층 구조.

</details>

```text
[MLFQ 다단계 피드백 큐 아키텍처]
|-- Q0 (최고 우선순위 - 타임 퀀텀 10ms, Round-Robin) <- 신규 프로세스 진입
|   `-- 10ms 소진 시 강등 -> Q1
|-- Q1 (중간 우선순위 - 타임 퀀텀 20ms, Round-Robin)
|   `-- 20ms 소진 시 강등 -> Q2
`-- Q2 (최저 우선순위 - 타임 퀀텀 40ms 또는 FCFS) <- CPU 집약 배치 작업 수렴
    `-- 주기적 우선순위 부스트 (주기 S마다 전체 프로세스를 Q0으로 일괄 승격)
```

선의 의미: 계층 및 타임 슬라이스 소진 시 강등 경로

| 구성요소 | 책임 |
|:---|:---|
| 최상위 큐(Q0) | 신규 작업 및 대화형 I/O 작업을 수용하여 최소 지연으로 즉각 실행 |
| 중간 계층 큐(Q1) | 일반적인 대화형 및 연산 혼합 작업의 시분할 순환 처리 |
| 최하위 큐(Q2) | 대규모 연산 배치 작업을 수용하며 긴 타임 슬라이스로 문맥 전환 비용 절감 |
| 강등 제어기 | 큐 내 누적 CPU 점유 시간을 추적하여 타임 퀀텀 초과 시 즉시 하위 큐로 이동 |
| 부스트 타이머 | 주기 $S$마다 모든 큐의 프로세스를 Q0으로 일괄 리셋하여 **기아 현상** 방지 |

#### 한줄 요약
- Q0(고속 대화형), Q1(혼합), Q2(배치 연산) 큐와 부스트 타이머가 통합되어 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **누적 시간 계측**: 프로세스가 단일 큐에 머무는 동안 사용한 총 CPU 시간을 합산하여 타임 퀀텀 초과 여부를 정밀 판정하는 방법.

</details>

```text
신규 프로세스 도착 -> 최상위 큐 Q0에 배치
        │
   스케줄러가 Q0에서 Round-Robin 방식으로 디스패치
        │
   현재 큐에서 타임 퀀텀을 모두 소진했는가?
   ┌────┴─────┐
  예           아니오 (타임 퀀텀 내 I/O 발생)
   │             │
한 단계 하위 큐로 I/O 완료 후 현재 큐 수준 유지
강등 (Demotion)  (대화형 우선순위 보존)
   │             │
   └────┬────────┘
        │
   부스트 주기 S 도달 시 -> 모든 프로세스를 최상위 Q0으로 일괄 승격 (기아 방지)
```

#### 한줄 요약
- 신규 Q0 진입 → 퀀텀 소진 시 하위 강등 → I/O 시 현재 큐 유지 → 주기적 Q0 승격 순으로 제어된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MLQ(Multilevel Queue)**: 큐 간의 이동이 불가능하고 프로세스 유형별로 큐가 영구 고정되는 정적 스케줄링.

</details>

| 스케줄링 기법 | MLFQ (다단계 피드백 큐) | MLQ (정적 다단계 큐) | CFS (완전 공정 스케줄러) |
|:---|:---|:---|:---|
| 큐 간 이동 | **실행 이력 기반 동적 이동** | 이동 불가 (정적 고정) | 가상 실행시간(vruntime) 순 정렬 |
| 작업 사전 지식 | **사전 정보 불필요 (자가 학습)** | 사전 분류 필수 (시스템/대화형/배치) | 사전 정보 불필요 |
| 기아 방지책 | **주기적 우선순위 부스트** | 큐별 타임 슬라이스 고정 분배 | vruntime 지연 프로세스 우선 배정 |
| 한계점 | 부스트 주기 및 큐 파라미터 튜닝 난해 | 프로세스 성격 변화 시 대처 불가 | 실시간 마감 기한 보장 한계 |

#### 한줄 요약
- 미분류 혼합 워크로드에는 MLFQ가, 정적 시스템 분리에는 MLQ가, 범용 Linux에는 CFS가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스케줄러 게이밍(Scheduler Gaming)**: 프로세스가 타임 퀀텀 만료 직전 의도적으로 짧은 I/O를 호출하여 CPU를 반납함으로써 상위 큐에서 내려오지 않는 꼼수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 의도적 99% CPU 점유 후 I/O 호출로 상위 큐 독점(**게이밍**) | 큐 단위 **누적 CPU 사용 시간(Account)** 추적 강등 | 스케줄러 어뷰징 차단 및 CPU 공정 배분 |
| 하위 큐에 배치 작업 누적 시 발생하는 **기아 현상** | **우선순위 부스트 주기($S=1\sim 2\text{s}$)** 설정 | 장기 대기 작업의 최소 CPU 실행 시간 확정 보장 |
| 큐 계층 수 및 타임 퀀텀 설정 오류로 인한 성능 왜곡 | 워크로드 I/O 비율 분석 기반 적응형 퀀텀 계층화(Q0: 10ms, Q1: 20ms) | 시스템 대화형 응답성 및 배치 처리량 최적화 |
| 고빈도 문맥 전환으로 인한 캐시 오염 | 최하위 배치 큐에 FCFS 및 긴 타임 퀀텀(100ms+) 적용 | 문맥 전환 오버헤드 축소 및 처리 효율 극대화 |

#### 한줄 요약
- 누적 시간 계측, 우선순위 부스트, 큐 퀀텀 계층화로 공정성과 응답성을 확보한다.

## Ⅶ. 결론

- 대화형과 배치의 혼재는 **MLFQ 적응형 스케줄링** 선택

#### 한줄 요약
- MLFQ는 사전 정보 없이도 프로세스의 특성을 동적으로 학습하여 응답성과 처리량을 동시에 최적화하는 스케줄링의 표준이다.
