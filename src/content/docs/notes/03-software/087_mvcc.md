## 미리 알고가기

- **다중 버전 동시성 제어(Multi-Version Concurrency Control, MVCC)**: 한 행의 여러 버전을 유지해 읽기와 쓰기의 대기를 줄이는 기법임
- **스냅숏(Snapshot)**: 트랜잭션이 일관되게 볼 수 있는 특정 시점의 논리적 데이터 모습임
- **읽기 뷰(Read View)**: 활성 트랜잭션과 커밋 경계를 기록해 보이는 버전을 판정하는 구조임
- **실행 취소 로그(Undo Log)**: 변경 전 값을 기록해 이전 버전 조회와 롤백에 사용하는 로그임
- **진공 청소·가비지 컬렉션(Vacuum/Garbage Collection)**: 아무 트랜잭션도 보지 않는 구버전을 회수하는 작업임
- **공유 잠금(Shared Lock)**: 여러 읽기는 허용하지만 충돌하는 쓰기를 기다리게 하는 잠금임
- **버전 체인(Version Chain)**: 현재 행에서 과거 행 버전을 차례로 찾도록 연결한 구조임
- **버전 팽창(Version Bloat)**: 오래된 스냅숏 때문에 회수하지 못한 행 버전이 쌓여 저장·조회 비용이 커지는 현상임

## Ⅰ. 개요

- 정의/개념: 스냅숏에 보이는 행 버전을 읽게 함
- **배경/필요성**: 읽기·쓰기 대기로 다중 버전 동시성 필요

### 쉽게 이해하기 (학습용)
- 읽는 거래는 시작 시점의 버전을 계속 보고 쓰는 거래는 새 버전을 만들어 상호 대기를 줄임

## Ⅱ. 특징

- 조회는 스냅샷을 참조해 쓰기 차단을 줄인다.
- 생성·종료 시점 메타데이터로 버전 가시성을 판정한다.
- 과거 버전이 쌓여 백그라운드 정리가 필요하다.
- 쓰기 충돌은 잠금·롤백·재시도로 보호한다.

### 쉽게 이해하기 (학습용)
- 서로 기다릴 필요가 없어 빠르지만 구버전이 공간을 차지해 정기적으로 비워야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 버전 메타데이터 | 생성·종료 시점으로 가시성 판정 |
| 스냅샷·읽기 뷰 | 볼 수 있는 커밋 경계와 활성 트랜잭션 범위를 정의함 |
| 버전 저장소·체인 | 영역 방식에 따라 현재와 과거 버전을 연결함 |
| 충돌 제어·정리기 | 동시 쓰기를 검증으로 처리하고 구버전을 회수함 |

```text
  버전제어
      ↓
  가시판정
      ↓
  스냅샷뷰
      ↓
  충돌검증
      ↓
  공간회수
```

> 요약: 버전 가시성·충돌 제어·구버전 정리

### 쉽게 이해하기 (학습용)
- 꼬리표와 기준 안경으로 과거 버전을 구별하고 청소함

## Ⅳ. 원리 및 절차 흐름도

```text
  스냅샷설정
      ↓
  가시성판정
      ↓
  버전조회
      ↓
  충돌처리
      ↓
  버전정리
```

| 절차 | 설명 |
|:---|:---|
| **스냅샷 설정** | 격리 수준에 따라 볼 수 있는 커밋 경계를 정함 |
| **버전 가시성 판정** | 버전 메타데이터를 스냅샷과 비교해 보이는 버전을 선택함 |
| **버전 조회** | 최신 버전 미가시 시 과거 버전 반환 |
| **갱신·충돌 처리** | 동시 쓰기는 검증이나 롤백 후 재시도로 제어함 |
| **구버전 정리** | 참조하지 않는 버전을 가비지 컬렉션으로 회수함 |

> 요약: 스냅샷 읽기·새 버전 기록·구버전 정리

### 쉽게 이해하기 (학습용)
- 늦게 쓴 내용은 숨기고 다 읽은 옛 일기는 청소부가 치우는 과정임

## Ⅴ. 종류 및 비교

| 비교축 | 다중 버전 동시성 제어 | 잠금 중심 제어 |
|:---|:---|:---|
| 핵심 특징 | 보이는 버전을 선택해 대기를 줄임 | 잠금 해제까지 충돌 접근이 대기함 |
| 일관성 기준 | 스냅숏 규칙으로 버전을 선택함 | 잠금 범위와 보유 기간으로 순서를 만듦 |
| 주요 위험 | 구버전 저장·가시성 판정 비용이 생김 | 경합·교착 상태·대기 비용이 생김 |
| 적용 기준 | 읽기 비중과 스냅숏 일관성이 중요함 | 충돌 쓰기의 엄격한 순서가 중요함 |

> 요약: 잠금 대기와 스냅샷 읽기를 비교

### 쉽게 이해하기 (학습용)
- MVCC는 독자에게 과거 버전을 보여 대기를 줄이고 잠금 방식은 충돌 작업의 순서를 직접 통제함

## Ⅵ. 실무 사례

1. 주문 조회 시스템은 제한 시간을 설정하고 버전 팽창률을 확인함
2. 재고 갱신 시스템은 재시도와 정리를 적용하고 실패율을 확인함

### 쉽게 이해하기 (학습용)
- 오래 열린 주문 조회를 제한하면 구버전을 제때 회수해 저장 공간과 조회 비용의 증가를 줄일 수 있음
- 재고 쓰기 충돌은 재시도하고 구버전은 정리해야 정확성과 공간 효율을 함께 유지할 수 있음

## Ⅶ. 결론

- 팽창·지연·충돌 비용을 관리하며 사용함

### 쉽게 이해하기 (학습용)
- MVCC는 읽기 대기를 줄이는 대신 구버전과 쓰기 충돌을 남기므로 스냅숏 수명·정리 지연·재시도를 관리해야 함
