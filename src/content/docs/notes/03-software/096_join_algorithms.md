## 미리 알고가기

- **중첩 반복 조인 (Nested Loops Join, NLJ)**: 바깥 행마다 안쪽 행을 탐색함
- **해시 조인 (Hash Join)**: 해시 테이블로 등치 키를 결합함
- **병합 조인 (Merge Join)**: 정렬된 두 입력을 순서대로 결합함
- **옵티마이저 (Optimizer)**: 통계와 비용으로 조인 방식을 선택함
- **중앙 처리 장치 (Central Processing Unit, CPU)**: 조인 연산을 수행함
- **입출력 (Input/Output, I/O)**: 저장장치의 읽기·쓰기 동작임
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **95백분위 지연 (95th Percentile Latency, p95)**: 요청 95%가 완료되는 지연 기준임
- **조인(Join)**: 공통 조건을 만족하는 여러 테이블의 행을 결합하는 연산임
- **바깥 입력(Outer Input)**: 중첩 반복 조인에서 먼저 읽어 반복을 시작하는 입력임
- **안쪽 입력(Inner Input)**: 바깥 입력의 각 행마다 일치 행을 찾는 입력임
- **빌드 입력(Build Input)**: 해시 조인에서 메모리 해시 테이블을 만드는 입력임
- **프로브 입력(Probe Input)**: 해시 테이블을 조회해 일치 행을 찾는 입력임
- **해시 버킷(Hash Bucket)**: 해시값이 같은 키와 행 위치를 모아 두는 저장 칸임
- **디스크 유출(Spill to Disk)**: 작업 메모리가 부족해 해시나 정렬의 중간 데이터를 임시 디스크에 쓰는 현상임

## Ⅰ. 개요

- **정의/개념**: 조건에 맞는 행을 결합하는 실행 방식임
- **배경/필요성**: 입력·정렬·메모리 차이로 조인 방식 선택 필요

### 쉽게 이해하기 (학습용)
- 한 명씩 찾기와 사전 만들기 및 명단 나란히 읽기를 선택하는 것임

## Ⅱ. 특징

- 입력 크기·조건·정렬·메모리가 최소 비용 방식을 가른다.
- 부적합한 조인 방식은 CPU·임시 디스크 비용을 키운다.

### 쉽게 이해하기 (학습용)
- 크기와 정렬 상태 및 작업 공간에 따라 적은 수고가 드는 방법이 다름

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 입력 집합 | 안팎과 빌드 및 프로브 순서를 정함 |
| 조인 조건 | 등치와 범위 조건으로 방식을 제한함 |
| 작업 메모리 | 해시 테이블과 정렬 버퍼 용량을 제공함 |
| 임시 경로 | 메모리 부족 시 디스크 작업을 수행함 |

```text
  입력크기
      ↓
  조건확인
      ↓
  메모리량
      ↓
  방식결정
```

> 요약: 입력과 조건 및 메모리가 조인 방식과 비용을 결정함

### 쉽게 이해하기 (학습용)
- 입력 크기와 조건 및 메모리에 맞춰 조인 방식을 선택함

## Ⅳ. 원리 및 절차 흐름도

```text
  규모추정
      ↓
  조건확인
      ↓
  후보평가
      ↓
  실측검증
```

| 절차 | 설명 |
|:---|:---|
| 규모추정 | 필터 뒤 입력 행 수를 추정함 |
| 조건확인 | 조건과 인덱스 및 메모리를 확인함 |
| 후보평가 | 조인 방식별 예상 비용을 비교함 |
| 실측검증 | 실제 행 수와 임시 입출력을 검증함 |

> 요약: 입력 조건으로 조인 방식을 정하고 실측 비용을 검증함

### 쉽게 이해하기 (학습용)
- 추정한 입력 규모로 후보를 정하고 실제 행 수와 디스크 유출을 확인해 선택이 적절했는지 검증함

## Ⅴ. 종류 및 비교

| 비교축 | NLJ | Hash Join | Merge Join |
|:---|:---|:---|:---|
| 핵심 특징 | 바깥 행마다 반복 탐색함 | 해시 테이블로 일치 버킷을 탐색함 | 정렬된 두 입력을 순차 비교함 |
| 적용 기준 | 소량 입력과 안쪽 인덱스에 적용함 | 대용량 등치 조인에 적용함 | 정렬 입력 재사용에 적용함 |
| 주요 위험 | 바깥 입력 증가 시 반복 비용이 커짐 | 메모리 부족 시 디스크 분할이 생김 | 정렬 비용이 크면 이점이 줄어듦 |

> 요약: 중첩은 소량, 해시는 등치, 병합은 정렬

### 쉽게 이해하기 (학습용)
- 소량은 반복을 쓰고 대량 등치는 해시와 병합을 씀

## Ⅵ. 실무 사례

1. 주문 상세는 중첩 반복 조인을 적용하고 조인 지연을 확인함
2. 집계 배치는 해시 조인·디스크 유출을 확인함

### 쉽게 이해하기 (학습용)
- 소량 주문 목록에서 상세를 인덱스로 찾을 때는 중첩 반복 조인이 불필요한 전체 읽기를 줄임
- 대량 등치 집계는 작은 입력으로 해시를 만들고 유출량을 감시해야 메모리 부족에 따른 지연을 통제할 수 있음

## Ⅶ. 결론

- 입력·조건·메모리에 맞는 조인 비용을 실측

### 쉽게 이해하기 (학습용)
- 조인 알고리즘은 이름만으로 우열을 정할 수 없으며 실제 입력 행 수·인덱스·정렬·메모리로 비용을 검증해야 함
