## 미리 알고가기

- **3단계 스키마(Three-level Schema Architecture)**: 데이터베이스 구조를 외부·개념·내부 계층으로 분리한 추상화 모델임
- **외부 스키마(External Schema)**: 사용자나 응용 프로그램별 데이터 표현과 접근 범위를 정의하는 계층임
- **개념 스키마(Conceptual Schema)**: 전체 데이터의 개체·관계·제약을 정의하는 단일 논리 계층임
- **내부 스키마(Internal Schema)**: 레코드·파일·인덱스·파티션의 물리 저장 구조를 정의하는 계층임
- **외부-개념 매핑(External-Conceptual Mapping)**: 사용자별 외부 표현을 개념 구조에 연결하는 변환 규칙임
- **개념-내부 매핑(Conceptual-Internal Mapping)**: 개념 구조를 물리 레코드와 접근 경로에 연결하는 변환 규칙임
- **데이터 독립성(Data Independence)**: 하위 계층의 변경을 매핑에서 흡수해 상위 계층의 변경을 줄이는 성질임
- **뷰(View)**: 기본 데이터에서 필요한 열과 행을 선택·변환해 제공하는 논리적 테이블임

## Ⅰ. 개요

- **정의/개념**: 데이터 구조를 외부·개념·내부로 분리함
- **배경/필요성**: 사용자·논리·저장 변경 결합으로 계층 분리 필요

### 쉽게 이해하기 (학습용)
- 화면과 장부 및 창고 배치를 세 층으로 나누고 번역표로 연결하는 구조임

## Ⅱ. 특징

- 여러 외부 스키마가 개념 스키마를 응용별 뷰로 표현한다.
- 개념 스키마가 개체와 관계를 저장 방식과 분리한다.
- 내부 스키마가 레코드·인덱스·파티션 배치를 정한다.
- 두 매핑이 계층 차이를 변환해 데이터 독립성을 지원한다.

### 쉽게 이해하기 (학습용)
- 각 층이 관심사를 분리해 변경이 다른 층으로 바로 번지는 것을 줄임

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 외부 스키마 | 응용에 필요한 데이터 표현과 접근 범위를 제공함 |
| 외부-개념 매핑 | 여러 외부 표현을 개념 스키마의 개체와 속성에 연결함 |
| 개념 스키마 | 데이터 의미와 관계 및 제약을 통합 정의함 |
| 개념-내부 매핑 | 개념 개체와 속성을 물리 레코드와 접근 경로에 연결함 |
| 내부 스키마 | 파일과 인덱스 및 파티션 등의 배치를 정의함 |

```text
  외부스키마
      ↓
  개념매핑
      ↓
  개념스키마
      ↓
  내부매핑
      ↓
  내부스키마
```

> 요약: 매핑이 표현·논리·물리 저장 차이 변환

### 쉽게 이해하기 (학습용)
- 여러 화면과 장부 및 저장 장치를 두 번역표로 연결함

## Ⅳ. 원리 및 절차 흐름도

```text
  외부정의
      ↓
  개념통합
      ↓
  내부설계
      ↓
  매핑검증
```

| 절차 | 설명 |
|:---|:---|
| **외부 스키마 정의** | 사용자별 데이터 표현과 접근 범위를 정의함 |
| **개념 스키마 통합** | 개체와 관계 및 제약을 하나의 모델로 통합함 |
| **내부 스키마 설계** | 파일과 인덱스 및 파티션 물리 배치를 설계함 |
| **매핑·독립성 검증** | 두 매핑을 정의하고 계층별 변경 영향을 검증함 |

> 요약: 외부 질의를 논리·물리로 변환해 반환

### 쉽게 이해하기 (학습용)
- 화면과 장부를 설계한 뒤 두 번역표가 공사를 가리는지 확인함

## Ⅴ. 종류 및 비교

| 비교축 | 외부 스키마 | 개념 스키마 | 내부 스키마 |
|:---|:---|:---|:---|
| 핵심 특징 | 사용자별 데이터 표현을 다룸 | 업무 전체 논리 구조를 다룸 | 저장 엔진 물리 구조를 다룸 |
| 관리 대상 | 뷰와 컬럼 및 표현 형식을 관리함 | 개체와 관계 및 제약을 관리함 | 인덱스와 파티션 등을 관리함 |
| 변경 예 | 화면별 컬럼과 별칭 변경을 수용함 | 테이블과 속성 및 관계 변경을 수용함 | 인덱스와 파티션 변경을 수용함 |
| 적용 기준 | 맞춤형 뷰를 제공할 때 적용함 | 통합 데이터 논리 구조를 설계할 때 적용함 | 인덱스 최적화 등 성능을 튜닝할 때 적용함 |
| 주요 위험 | 뷰 난립·권한 누락 | 변경 영향·업무 규칙 충돌 | 물리 종속·튜닝 복잡도 |

> 요약: 외부는 표현, 개념은 논리, 내부는 저장

### 쉽게 이해하기 (학습용)
- 외부는 화면이고 개념은 업무 의미이며 내부는 물리 배치를 담당함

## Ⅵ. 실무 사례

1. 공용 DB는 외부 뷰를 적용하고 변경 영향 응용 수를 확인함
2. 대용량 테이블은 내부 파티션을 변경하고 응용 쿼리 변경을 확인함

### 쉽게 이해하기 (학습용)
- 공용 데이터베이스는 외부 뷰로 응용별 표현을 제공해 개념 스키마 변경의 영향을 제한함
- 대용량 테이블의 내부 파티션을 바꾼 뒤 응용 질의가 그대로 동작하면 물리 변경이 매핑에서 흡수된 것임

## Ⅶ. 결론

- 세 계층과 두 매핑으로 변경 영향을 분리

### 쉽게 이해하기 (학습용)
- 3단계 스키마는 개념 스키마를 의미의 중심으로 두고 두 매핑이 외부 표현과 내부 저장의 차이를 변환하는 구조임
