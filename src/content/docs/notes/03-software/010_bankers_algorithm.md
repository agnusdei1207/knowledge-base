## 미리 알고가기

- **은행원 알고리즘(Banker's Algorithm)**: 안전 상태를 유지할 요청만 승인하는 회피 기법
- **가용량(Available)**: 현재 즉시 할당할 수 있는 자원 벡터
- **최대 요구량(Max)**: 프로세스별 자원 최대 요구 행렬
- **할당량(Allocation)**: 프로세스별 현재 자원 할당 행렬
- **잔여 요구량(Need)**: 최대 요구량에서 할당량을 뺀 행렬
- **검사 가용량·완료 여부(Work·Finish)**: 안전 순서 탐색용 가용량·완료 표식
- **안전 순서(Safe Sequence)**: 모든 프로세스를 끝낼 수 있는 실행 순서
- **요청 벡터(Request Vector)**: 프로세스가 추가로 요구한 자원 수량
- **벡터·행렬(Vector·Matrix)**: 벡터는 자원 종류별 수량의 한 줄 배열이고 행렬은 프로세스별 벡터를 쌓은 표로서 가용량·요구량·할당량을 표현한다.
- **어베일러블·맥스·앨로케이션·니드(Available·Max·Allocation·Need)**: 각각 ‘어베일러블·맥스·앨로케이션·니드’로 읽는 알고리즘의 관례 상태 이름이며 현재 가용 벡터·최대 요구 행렬·현재 할당 행렬·남은 요구 행렬을 나타낸다.
- **워크·피니시(Work·Finish)**: 각각 ‘워크·피니시’로 읽는 안전성 검사의 관례 변수 이름이며 Work는 가상 회수 자원 벡터, Finish는 각 프로세스의 완료 가능 여부를 기록한다.
- **작거나 같음 기호($\le$)**: ‘작거나 같다’로 읽고 왼쪽 값이 오른쪽 한도를 넘지 않음을 나타내는 수학 관례 표기이며 Request가 Need와 Available 이하인지, Need가 Work 이하인지 검사한다.
- **가상 할당(Tentative Allocation)**: 요청을 실제 승인하기 전에 자원 상태에 임시 반영해 안전 순서가 유지되는지 검사하고 불안전하면 복원하는 동작
- **불리언 참·거짓(Boolean True·False)**: 불리언은 두 논릿값만 갖는 자료형이며 Finish의 참은 완료 가능한 프로세스, 거짓은 아직 안전 순서에 넣지 못한 프로세스를 나타낸다.
- **배치 시스템(Batch System)**: 작업별 최대 메모리를 미리 선언받고 여러 작업을 묶어 실행하므로 은행원 알고리즘의 사전 요구량 조건을 충족할 수 있는 시스템
- **임베디드 제어기(Embedded Controller)**: 제한된 장치 자원을 제어하는 전용 컴퓨터로서 작업별 최대 점유량을 바탕으로 요청을 승인할 수 있다.

## Ⅰ. 개요

- 정의/개념: 안전 순서를 보존하는 교착상태 회피 기법
- **배경/필요성**: 불안전 할당이 교착을 낳아 사전 검사 필요

### 쉽게 이해하기 (학습용)

- 모든 고객에게 남은 대출을 해 줘도 차례대로 상환받을 수 있을 때만 새 대출을 승인한다.

## Ⅱ. 특징

- 최대 요구량을 모르면 안전 상태를 판정할 수 없다
- 안전 순서가 있는 가상 할당만 승인한다
- 보수적 승인은 자원 이용률을 낮출 수 있다
- 프로세스·자원 증가는 검사 비용을 높인다

### 쉽게 이해하기 (학습용)

- 고객마다 앞으로 필요한 최대 금액을 알고 모두 상환할 순서를 찾을 수 있을 때만 돈을 빌려준다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    P[프로세스]
    R[자원 집합]
    subgraph B[은행원 알고리즘 경계]
        C[요청 제어기]
        S[자원 상태]
        A[안전성 검사기]
        C -->|가상 할당| S
        S -->|Available·Need| A
        A -->|안전·불안전| C
    end
    P -->|자원 요청| C
    C -->|승인·보류| P
    R -->|총 자원량| S
```

| 설계 요소 | 설명 |
|:---|:---|
| 요청 제어기 | 요청 한도 검사 후 가상 할당·복원 통제 |
| 자원 상태 | Available·Max·Allocation·Need 관리 |
| 안전성 검사기 | Work·Finish로 안전 순서 존재 판정 |

> 요약: 가상 할당 후 안전 순서가 존재할 때 요청 승인

### 쉽게 이해하기 (학습용)

- 요청을 장부에 먼저 반영하고 모든 고객에게 차례로 돈을 돌려받을 수 있는지 검사한 뒤 승인한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant P as 프로세스
    participant C as 요청 제어기
    participant S as 자원 상태
    participant A as 안전성 검사기
    P->>C: 자원 요청
    C->>S: 요청 한도 검사
    C->>S: 가상 할당
    S->>A: 안전 순서 탐색
    A-->>C: 안전 상태 판정
    alt 안전 상태
        C->>S: 할당 확정
    else 불안전 상태
        C->>S: 할당 복원
    end
```

| 절차 | 설명 |
|:---|:---|
| 자원 요청 | 프로세스가 요청 벡터 제출 |
| 요청 한도 검사 | Request≤Need와 Request≤Available 검사 |
| 가상 할당 | 가용량 감소, 할당량 증가, 필요량 감소 |
| 안전 순서 탐색 | Need≤Work인 프로세스를 반복 선택 |
| 안전 상태 판정 | 모든 Finish가 참이면 안전 상태 |
| 할당 확정 | 가상 할당 결과를 실제 상태로 유지 |
| 할당 복원 | 불안전하면 이전 상태로 복원·요청 보류 |

> 요약: 요청을 가상 반영하고 안전 순서 존재 여부로 확정

### 쉽게 이해하기 (학습용)

- 새 대출을 장부에 가정하고 모든 고객의 상환 순서를 만들 수 있으면 확정하며 아니면 되돌린다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 안전 상태 | 불안전 상태 |
|:---|:---|:---|
| 핵심 특징 | 안전 순서가 하나 이상 존재 | 안전 순서가 존재하지 않음 |
| 적용 기준 | 모든 Finish가 참 | 일부 Finish가 거짓 |
| 주요 위험 | 반복 검사 비용 | 교착상태로 진행 가능 |

> 요약: 불안전 상태는 교착상태가 아니지만 진행 가능성이 존재

### 쉽게 이해하기 (학습용)

- 모두 상환할 순서가 있으면 안전하고 지금 막히지 않아도 그런 순서가 없으면 불안전하다.

## Ⅵ. 실무 사례

1. 배치 시스템은 작업별 최대 메모리를 선언받아 안전 순서 검사

### 쉽게 이해하기 (학습용)

- 배치 시스템은 모든 작업이 끝날 메모리 배정 순서를 확인한 뒤 새 작업을 받는다.

## Ⅶ. 결론

- 최대 요구량·검사 비용으로 은행원 알고리즘 적용 결정

### 쉽게 이해하기 (학습용)

- 최대 사용량을 미리 알 수 있고 검사 시간이 요청 지연 한도 이내인 작업에 적용한다.
