## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **은행원 알고리즘(Banker's Algorithm)**: 요청을 가상 할당한 뒤 모든 프로세스를 끝낼 안전 순서가 남을 때만 승인하는 교착 회피 알고리즘이다.

</details>

- 정의/개념: 요청을 가상 할당한 뒤 안전 순서가 남을 때만 승인하는 **교착 회피 알고리즘**이다.
- 배경/필요성: 현재 가용량만 보고 할당하면 향후 **교착상태로 진행**이 발생한다.

#### 한줄 요약

- 모든 프로세스의 **안전 순서**가 남는 요청만 승인이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **가용량(Available)**: 현재 즉시 할당할 수 있는 자원 벡터이다.
- **최대 요구량(Max)**: 프로세스별 최대 자원 요구 행렬이다.
- **할당량(Allocation)**: 프로세스별 현재 자원 보유 행렬이다.
- **잔여 요구량(Need)**: 최대 요구량에서 할당량을 뺀 행렬이다.
- **가상 할당(Tentative Allocation)**: 요청을 임시 반영해 안전 순서가 유지되는지 검사하고 불안전하면 복원하는 동작이다.

</details>

- **최대 요구량**으로 안전 상태를 판정한다.
- **가상 할당•안전 순서** 확인 후 승인이 핵심이다.
- **가용량•잔여 요구량** 벡터 비교로 다중 자원 안전성을 판정한다.

#### 한줄 요약

- **최대 요구량•가상 할당** 기반 안전 상태를 판정한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **요청 벡터(Request Vector)**: 프로세스가 자원 종류별로 추가 요구한 수량의 배열이다.
- **안전 순서(Safe Sequence)**: 모든 프로세스를 차례로 완료시킬 수 있는 실행 순서이다.
- **프로세스 인덱스($i$)**: 자원 상태 행렬에서 각 프로세스 행을 구분하는 번호이다.
- **완료 여부(Finish)**: 안전성 검사에서 해당 프로세스가 잔여 자원을 받아 끝날 수 있는지를 기록하는 논리값이다.

</details>

```text
[요청 프로세스] -- [요청 제어기] -- [자원 상태]
                                         |
                                  [안전성 검사기]
```

선의 의미: 요청 제어기는 요청 프로세스의 요구를 자원 상태와 대조하고, 안전성 검사기는 그 자원 상태가 안전 순서를 허용하는지 검사한다.

| 구성요소 | 책임 |
|:---|:---|
| 요청 프로세스 | **추가 자원량 제출** |
| 요청 제어기 | **한도•가상 할당 통제** |
| 자원 상태 | **가용•할당•잔여량 보관** |
| 안전성 검사기 | **안전 순서 탐색** |

프로세스 $i$의 잔여 요구량과 요청 선행 조건:

$$
\mathrm{Need}_i=\mathrm{Max}_i-\mathrm{Allocation}_i,\qquad
\mathrm{Request}_i\le\mathrm{Need}_i,\quad
\mathrm{Request}_i\le\mathrm{Available}
$$

- **벡터 비교**: 자원 종류별 요청량과 가용량을 각각을 비교한다.
- **분석 전제**: 최대 요구량의 사전 선언과 자원 회수 가능성 가정이다.
- **안전 승인 조건**: 가상 할당 뒤 모든 Finish가 참인 순서 존재이다.

#### 한줄 요약

- 자원 상태와 **안전성 검사기** 기반 요청 승인 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **요청 한도 검사**: Request가 Need와 Available 이하인지 확인하는 단계이다.
- **가상 할당**: 요청을 임시 반영해 승인 이후의 자원 상태를 만드는 단계이다.
- **Work•Finish 초기화**: 가상 가용량과 프로세스별 완료 여부를 설정하는 단계이다.
- **안전 순서 탐색**: Need가 Work 이하인 프로세스를 완료 처리하고 자원을 가상 회수하는 반복이다.
- **확정•복원 판정**: 모든 Finish가 참이면 할당을 확정하고 아니면 이전 상태로 되돌리는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 추가 자원 요청              │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 요청 한도 검사           │
│ Request ≤ Need              │
│ Request ≤ Available         │
└───────┬──────────────────────┘
        ├─ 위반 ────────────────▶ [거절]
        │ 충족
        ▼
┌──────────────────────────────┐
│ 2. 가상 할당                │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. Work•Finish 초기화       │
└──────────────┬───────────────┘
               ▼
╔══════════════════════════════╗
║ 반복: Finish=false이며       ║
║       Need≤Work인 행 존재    ║
║ 4. 안전 순서 탐색           ║
║ Finish=true                 ║
║ Work += Allocation          ║
╚══════════════╤═══════════════╝
               │ 선택 가능한 행 없음
               ▼
┌──────────────────────────────┐
│ 5. 확정•복원 판정           │
└───────┬──────────────────────┘
        ├─ 모든 Finish=true ────▶ [할당 확정]
        └─ 완료 불가 존재 ──────▶ [상태 복원•거절]
```

**동작 원리**

- **1. 요청 한도 검사**: Request와 Need•Available 벡터를 비교한다.
- **2. 가상 할당**: 요청을 Available•Allocation•Need에 임시를 반영한다.
- **3. Work•Finish 초기화**: Work와 미완료 집합 설정한다.
- **4. 안전 순서 탐색**: 완료 가능 프로세스 자원을 가상 회수이다.
- **5. 확정•복원 판정**: 전수 완료 시 확정, 불가 시 복원한다.

#### 한줄 요약

- 가상 할당 후 **안전 순서** 존재 시에만 확정이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **안전 상태(Safe State)**: 모든 프로세스를 끝낼 안전 순서가 하나 이상 존재하는 자원 할당 상태이다.
- **불안전 상태(Unsafe State)**: 현재 교착은 아니어도 안전 순서가 없어 향후 교착으로 진행할 수 있는 상태이다.

</details>

| 자원 할당 상태 | 판정 결과 | 할당 의미 |
|:---|:---|:---|
| **안전 상태** | 모든 프로세스를 끝낼 **안전 순서 존재** | 현재 요청을 반영해도 완료 가능성 유지 |
| **불안전 상태** | 일부 프로세스를 끝낼 수 없어 **안전 순서 부재** | 현재 교착은 아니어도 교착으로 진행 가능 |

> 요약: 불안전 상태는 교착이 아니지만 **안전 순서 부재**로 **교착 진행 가능**이 핵심이다.

#### 한줄 요약

- **안전 순서** 존재 여부로 안전•불안전 상태를 구분한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **원자성(Atomicity)**: 검사와 할당 변경이 전부 성공하거나 전부 취소되어 중간 상태가 드러나지 않는 성질이다.
- **버전 검증(Version Validation)**: 검사 시작과 확정 시점의 상태 번호를 비교해 동시 변경 여부를 확인하는 방법이다.
- **오버헤드(Overhead)**: 본래 작업 외에 안전성 검사와 상태 관리 때문에 추가로 드는 시간과 자원이다.
- **예약 정책(Reservation Policy)**: 장기 대기 요청에 우선순위나 자원 몫을 미리 배정해 진행 기회를 보장하는 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 최대 요구량을 과장•변경해 **자원 이용률 저하** | 선언 상한 검증과 **실사용량 피드백** | **보수적 자원 예약** 완화 |
| 동시 요청 중 검사•할당 상태가 바뀌어 **판정 경쟁** | 자원 갱신의 **원자성•버전 검증** | **안전성 판정 일관성** 유지 |
| 프로세스•자원 증가로 **안전성 검사 지연** 확대 | 검사 비용 계측과 **적용 범위 제한** | **제어 오버헤드** 상한 유지 |
| 안전 상태만 우선해 특정 요청이 **장기 대기** | 대기시간•우선순위 기반 **예약 정책** | 안전성과 **진행 공정성** 균형 |

#### 한줄 요약

- 원자적 검사와 **버전 검증**으로 승인 일관성을 유지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **최대 요구량 신뢰성**: 자원 상한을 정확히 알 수 있는지의 적용 기준이다.
- **검사 지연**: 안전성 검사 비용을 감당할 수 있는지의 적용 기준이다.

</details>

- 최대 요구량을 신뢰할 수 있고 검사 지연이 허용되면 **은행원 알고리즘**으로 **요청 승인**이 핵심이다.

#### 한줄 요약

- 최대 요구량 신뢰와 **검사 지연** 허용 시를 적용한다.
