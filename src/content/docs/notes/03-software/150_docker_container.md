## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **도커 컨테이너(Docker Container)**: 이미지로 애플리케이션과 의존성을 묶고 네임스페이스•제어 그룹으로 격리해 실행하는 프로세스 단위 환경이다.

</details>

- 정의/개념: 이미지로 애플리케이션과 의존성을 묶고 호스트 커널의 네임스페이스•제어 그룹으로 격리해 실행하는 **도커 컨테이너(Docker Container)** 환경
- 배경/필요성: 서버별 라이브러리•설정 차이로 **동일 빌드 실행 결과** 불일치

#### 한줄 요약

- 같은 조리법과 재료를 봉인한 상자를 어느 주방에서든 열어 쓰듯, 이미지가 애플리케이션과 의존성을 묶어 같은 실행 환경을 반복 만든다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **계층형 이미지**: 읽기 전용 파일 계층을 여러 이미지와 컨테이너가 공유하는 특성이다.
- **네임스페이스(Namespace)**: 프로세스가 볼 수 있는 커널 자원의 범위를 분리하는 기능이다.
- **제어 그룹(Control Group, cgroup)**: 프로세스의 CPU•메모리 사용량을 제한하는 기능이다.
- **중앙처리장치(Central Processing Unit, CPU)**: 명령어를 실행하는 컴퓨팅 자원이다.
- **상태 외부화**: 교체되는 컨테이너 내부가 아니라 볼륨•외부 저장소에 영속 데이터를 보관하는 방식이다.

</details>

- 읽기 전용 계층을 공유하는 **계층형 이미지**
- 네임스페이스•cgroup 기반 **커널 격리**
- 새 이미지 교체와 **상태 외부화** 의 불변 배포

#### 한줄 요약

- 같은 건물의 방들이 벽과 전기 차단기를 나눠 쓰듯, Namespace가 보이는 자원을 가르고 cgroup이 각 컨테이너의 사용량을 제한한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **네임스페이스•cgroup**: 커널 자원의 가시 범위와 CPU•메모리 사용량을 통제하는 구성요소이다.
- **도커파일(Dockerfile)**: 이미지 계층과 기본 실행값을 선언하는 빌드 명세이다.
- **빌더**: 도커파일 명령에 따라 이미지 계층을 만드는 구성요소이다.
- **레지스트리(Registry)**: 이미지 계층•태그•내용 다이제스트를 저장•배포하는 구성요소이다.
- **컨테이너 런타임(Container Runtime)**: 루트 파일시스템(Root File System, RootFS)과 실행 설정으로 격리 프로세스를 생성하는 구성요소이다.
- **볼륨**: 컨테이너 수명과 분리된 영속 데이터 경로이다.
- **외부 저장소**: 여러 컨테이너의 데이터와 로그를 보존하는 구성요소이다.

</details>

```text
[Docker 컨테이너 실행 구조]
          |
          +-- [Dockerfile•빌더]
          |
          +-- [레지스트리]
          |
          +-- [컨테이너 런타임]
          |
          +-- [네임스페이스•cgroup]
          |
          +-- [볼륨•외부 저장소]
```

선의 의미: Dockerfile•빌더가 만든 이미지 계층은 레지스트리에 보관되고, 컨테이너 런타임은 해당 이미지를 네임스페이스•cgroup으로 격리하며 볼륨•외부 저장소에 영속 상태를 연결한다.

| 구성요소 | 책임 |
|:---|:---|
| Dockerfile•빌더 | 명령별 **이미지 계층•실행값** 생성 |
| 레지스트리 | 계층•태그•**다이제스트** 저장 |
| 컨테이너 런타임 | RootFS와 설정으로 **격리 프로세스** 생성 |
| 네임스페이스•cgroup | 커널 자원의 **가시성•사용량** 통제 |
| 볼륨•외부 저장소 | 컨테이너와 분리한 **영속 데이터** 보존 |

#### 한줄 요약

- 빌더가 만든 봉인 상자를 레지스트리에 두면 런타임이 이를 받아 개인 방과 전기 한도를 붙이고, 버려지면 안 되는 자료는 외부 보관함에 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **이미지 계층•다이제스트 생성**: 빌드 명령별 결과와 내용 식별값을 불변 원본으로 만드는 단계이다.
- **매니페스트•계층 검증**: 요청한 다이제스트와 이미지 계층의 무결성을 확인하는 단계이다.
- **루트 파일시스템 조립**: 읽기 전용 이미지 계층과 컨테이너 쓰기 계층을 결합하는 단계이다.
- **격리•자원•프로세스 설정**: 네임스페이스와 제어 그룹으로 가시 범위와 자원 한도를 적용하는 단계이다.
- **볼륨•외부 상태 연결**: 컨테이너 교체와 무관하게 남을 데이터 경로를 마운트하는 단계이다.

</details>

```text
[이미지 빌드]
Dockerfile
    |
    v
1. 이미지 계층•다이제스트 생성
    |
    v
레지스트리에 불변 이미지 저장

[컨테이너 시작]
이미지 다이제스트
    |
    v
2. 매니페스트•계층 검증
    |
    v
3. 루트 파일시스템 조립
    |
    v
4. 격리•자원•프로세스 설정
    |
    v
5. 볼륨•외부 상태 연결
    |
    v
격리 프로세스 실행
```

**동작 원리**

- **1. 이미지 계층•다이제스트 생성**: 빌드 결과를 불변 원본으로 식별
- **2. 매니페스트•계층 검증**: 요청 이미지의 무결성 확인
- **3. 루트 파일시스템 조립**: 읽기 전용•쓰기 계층 결합
- **4. 격리•자원•프로세스 설정**: 가시 범위와 자원 한도 적용
- **5. 볼륨•외부 상태 연결**: 교체와 분리한 데이터 경로 마운트

#### 한줄 요약

- 창고에서 봉인 상자의 지문을 확인해 꺼낸 뒤 개인 방과 전기 한도를 만들고, 상자를 교체해도 남을 자료는 외부 보관함에 연결한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **컨테이너**: 호스트 커널을 공유하는 격리 프로세스로 빠른 배포와 수평 확장에 적합한 실행 방식이다.
- **가상 머신(Virtual Machine, VM)**: 하이퍼바이저 위에서 독립 게스트 운영체제까지 실행해 커널 경계를 분리하는 가상화 방식이다.

</details>

| 실행 가상화 방식 | 컨테이너 | 가상 머신 |
|:---|:---|:---|
| 적용 기준 | **빠른 배포•수평 확장** | **커널 격리•전체 OS** 제어 |
| 핵심 특징 | 호스트 커널 공유 **격리 프로세스** | 하이퍼바이저 위 **게스트 OS** |
| 한계 | 커널 취약점의 **공유 영향** | 느린 시작•큰 **자원 점유** |

#### 한줄 요약

- 컨테이너는 같은 건물 안의 잠긴 방이라 빨리 만들 수 있고, 가상 머신은 기초 설비까지 나눈 별도 건물이라 무겁지만 커널 경계가 더 분명하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **공급망 위협**: 이미지 빌드 경로에 악성 또는 취약한 소프트웨어 계층이 유입되는 문제이다.
- **소프트웨어 자재 명세서(Software Bill of Materials, SBOM)**: 이미지에 포함된 소프트웨어 구성요소와 버전을 기록한 목록이다.
- **다이제스트 배포**: 변경 가능한 태그 대신 이미지 내용의 고유 해시를 지정해 동일 원본을 배포하는 방식이다.
- **다단계 빌드**: 빌드 도구와 최종 실행 파일을 서로 다른 단계로 분리해 실행 이미지에는 필요한 결과만 남기는 방식이다.
- **비루트 사용자**: 관리자 권한 없이 컨테이너 프로세스를 실행하는 주체이다.
- **기능 권한 제거**: 불필요한 리눅스 기능 권한을 제거하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 태그 재사용으로 달라지는 **배포 원본** | 버전 고정•**다이제스트** 배포 | 환경별 **이미지 차이 방지** |
| 빌드 경로로 유입되는 **공급망 위협** | 신뢰 원본•SBOM•**이미지 서명** | 악성•취약 **계층 차단** |
| 빌드 도구가 남은 **대형 이미지** | 다단계 빌드•최소 **기반 이미지** | 전송량•**공격 표면 감소** |
| 루트 사용자•리눅스 기능의 **과도 권한** | **비루트 사용자•기능 권한 제거** 와 읽기 전용 | 컨테이너 탈출의 **피해 범위 완화** |
| 교체 시 사라지는 **로컬 상태** | 볼륨•외부 저장•**중앙 로그** | 데이터•감사 **증적 보존** |

#### 한줄 요약

- 조립 공구는 최종 배송 상자에서 빼고 상자 지문을 고정하며, 상자를 버려도 남아야 할 자료와 기록은 외부 보관함에 둔다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **커널 격리**: 신뢰 경계상 운영체제 커널 자체를 분리해야 할 때 가상 머신을 선택하는 기준이다.
- **동일 커널•불변 배포**: 호스트 커널을 공유하면서 이미지를 교체 단위로 사용하는 컨테이너 적합 조건이다.
- **선택 기준**: 커널 격리와 불변 배포 요구를 비교하는 축이다.

</details>

- **동일 커널•불변 배포**면 컨테이너, **커널 격리** 필요 시 가상 머신

#### 한줄 요약

- 같은 커널에서 빠르게 교체할 서비스는 컨테이너로 묶고, 커널 자체를 분리해야 하는 신뢰 경계라면 가상 머신을 선택한다.
