## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다중 프로세서 스케줄링(Multiprocessor Scheduling)**: CPU 코어가 수십 개 달린 환경에서 프로세스들을 어떻게 줄 세우고 코어에 분배할지(캐시와 락의 전쟁) 결정하는 뇌지컬 분배기이다.
- **SQMS (단일 큐 멀티프로세서 스케줄링)**: 전 세계 CPU 코어가 단 하나의 거대한 대기열(글로벌 큐)에 달라붙어서 락(Lock)을 걸고 작업을 뺏어가는 구식 배급 방식이다.
- **MQMS (다중 큐 멀티프로세서 스케줄링)**: CPU 코어마다 자기만의 밥그릇(로컬 큐)을 꿰차서, 남의 눈치 안 보고 내 큐에 있는 작업만 죽어라 패는 현대적 분업 방식이다.

</details>

- 정의: 멀티코어의 극강 성능을 뽑기 위해 전역 큐 하나로 퉁칠 건지(SQMS), 코어마다 큐를 찢을 건지(MQMS)를 가르는 **스케줄링 2대 아키텍처**
- 배경: 코어가 많아질수록 큐 1개에 동시에 달려들어 **락(Lock) 병목**이 터지거나, 코어별 부하가 개판 나는 걸 통제해야 하기 때문

#### 한줄 요약

- 코어 여러 개를 굴릴 때, 큐 하나로 줄 세울지(SQMS), 코어마다 줄 세울지(MQMS) 결정하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **캐시 친화도(Cache Affinity)**: CPU 코어 안에 있는 L1/L2 캐시에 예전에 쓰던 데이터가 묻어 있으니, 무조건 전에 돌던 코어에 다시 밀어 넣어야 성능이 떡상하는 성질이다.
- **작업 훔치기(Work Stealing)**: MQMS에서 내 밥그릇(큐)이 다 비어 노는 코어가 생기면, 옆 코어의 밥그릇을 뒤져서 작업을 서리해 오는 합법적 도둑질(부하 분산) 기술이다.

</details>

- 중앙 큐 하나를 공유해서 복잡한 분산 똥꼬쇼가 필요 없는 **SQMS**의 무지성 단순함.
- 코어마다 큐를 찢어서 락 병목을 부수고 **Cache Affinity(캐시 친화도)**를 떡상시키는 **MQMS**.
- MQMS에서 놀고먹는 코어를 굴리기 위해 **작업 훔치기(Work Stealing)**로 강제 부하 평탄화를 꽂음.

#### 한줄 요약

- SQMS는 락(Lock)이 터지고, MQMS는 락 없이 캐시 온기를 지키되 도둑질(분산)이 필수다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **락 경합(Lock Contention)**: SQMS에서 코어 64개가 작업 1개 꺼내 가려고 동시에 전역 큐에 락을 거느라, 63개가 멍 때리는 미친 성능 병목이다.

</details>

```text
[ 다중 프로세서 스케줄링 십자포화 구조 ]

[ SQMS (Single Queue) ]        [ MQMS (Multi Queue) ]

   [ 전역 실행 큐 ]              [CPU 0 큐]   [CPU 1 큐]
  (락 하나로 꽉 막힘)           (각자 자기 큐만 팸)
  /      │       \               │      훔치기     │
 ▼       ▼       ▼              ▼       ◀─▶     ▼
[CPU 0] [CPU 1] [CPU 2]        [CPU 0]        [CPU 1]
(캐시 다 꼬이고 난리남)      (캐시 유지, 락 경합 없음)
```

| 구성요소 | 책임 |
|:---|:---|
| 작업 배치기 | 스케줄러가 새로 들어온 작업을 SQMS 큐에 넣을지, MQMS의 특정 코어 큐에 꽂을지 정하는 사령관 |
| **전역 실행 큐 (SQMS)** | 모든 코어가 침 흘리며 달려드는 거대한 대기열로, **락(Lock)** 병목의 근원지 |
| **코어별 큐 (MQMS)** | 코어마다 독상으로 받는 밥그릇으로, 경합 제로에 캐시 온기가 남아있는 꿀통 |
| CPU 코어 집합 | 큐에서 멱살 잡고 끌고 온 작업을 진짜로 실행하는 노예들 |
| 부하 분산기 | 코어 하나만 뼈 빠지게 일할 때 큐 개수를 보고 **작업 훔치기**를 때려버리는 감시관 |

#### 한줄 요약

- 큐가 1개면 다 같이 락(Lock) 걸려 멈추고, 코어마다 큐가 있으면 캐시가 유지된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **밀어내기/당겨오기(Push/Pull Migration)**: 큐에 일이 너무 많은 놈이 남한테 일을 던지는 게 Push, 다 놀아서 심심한 놈이 남의 일을 뺏어오는 게 Pull인 부하 분산 스킬이다.

</details>

```text
[ 다중 프로세서 큐 디스패치 십자포화 흐름 ]

[ SQMS 실행 경로 ]
┌──────────────────────────────┐
│ 1. 전역 큐 락(Lock) 획득 대기│
└──────────────┬───────────────┘
               ▼ (락 뚫음)
┌──────────────────────────────┐
│ 2. 디스패치 및 실행 (캐시 꽝)│
└──────────────────────────────┘

[ MQMS 실행 경로 ]
┌──────────────────────────────┐
│ 1. 로컬 큐에서 다이렉트 선택 │
└──────────────┬───────────────┘
               ▼ (캐시 온기 유지)
┌──────────────────────────────┐
│ 2. 디스패치 및 실행          │
└──────────────┬───────────────┘
               ▼ (내 큐 텅 빔)
┌──────────────────────────────┐
│ 3. 편차 탐지 및 작업 훔치기  │
└──────────────────────────────┘
```

### 동작 원리

1. SQMS 디스패치: 전역 큐에 락 걸고 작업 꺼내서 빈 코어에 던짐 (캐시 재수 없으면 꼬임).
2. MQMS 로컬 디스패치: 코어가 자기 큐에서 바로 작업 꺼내서 팸 (이전에 돌던 코어라 캐시 빵빵함).
3. MQMS 작업 훔치기: 로컬 큐 다 비우고 노는 코어가 생기면 옆 코어 큐에서 훔쳐 와서(**Pull**) 강제 분산시킴.

#### 한줄 요약

- SQMS는 락을 뚫고 억지로 가져가고, MQMS는 자기 큐만 패다가 심심하면 남의 걸 훔친다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **리눅스 CFS 다중 큐(Linux CFS Multi-Queue)**: 리눅스가 쓰는 스케줄러(CFS)가 코어별로 `cfs_rq`를 파놓고, 백그라운드에서 주기적으로 도둑질(`load_balance`)을 시키는 현대 MQMS의 표본이다.

</details>

| 기능 비교 | **SQMS (단일 큐)** | **MQMS (다중 큐)** |
|:---|:---|:---|
| 확장성 (코어 64개 꽂음) | 큐 하나에 코어 64개가 락(Lock) 경쟁하느라 다 뒤짐 | 자기 큐만 봐서 코어가 수백 개여도 선형적으로 떡상함 |
| 캐시 친화도 (L1/L2) | 매번 이사 다니느라 캐시가 다 리셋돼서 성능 깎임 | 맨날 돌던 코어에서 계속 도니까 캐시 적중률 미쳐 날뜀 |
| 런타임 비용 | 부하 분산 짤 필요도 없이 자연스럽게 공평해짐 | 코어끼리 일감 편차 나면 계속 감시하고 훔쳐야 돼서 오버헤드 큼 |
| 활용 무대 | 코어 2~4개짜리 옛날 쌍팔년도 OS | 현재 스마트폰부터 수백 코어 리눅스 서버까지 **압도적 국룰** |

#### 한줄 요약

- 확장성과 캐시 효율이 씹어먹는 수준이라, 현대 모든 OS는 MQMS를 국룰로 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **어피니티 마스크(Affinity Mask, taskset)**: OS가 지 맘대로 작업 훔쳐서 코어 이사시키는 꼴을 못 보겠을 때, "넌 죽어도 1번 코어에서만 돌아!"라고 목줄을 채워버리는 커널 락킹 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| MQMS 썼더니 어떤 코어는 일 100개 쌓였고 옆 코어는 팽팽 놂 | **작업 훔치기(Work Stealing)**를 주기적으로 갈겨서 부하 평탄화시킴 | 일 안 하고 노는 코어의 뒤통수를 쳐서 전체 시스템 가용률 100% 사수 |
| 작업 훔치기로 툭하면 이사 다녀서 캐시가 다 날아가 버벅임 | **`taskset` (CPU Pinning)**으로 멱살 잡고 코어 1개에 강제 고정 | 캐시 히트율을 극한으로 쥐어짜서 깡연산 성능 극대화 |
| 소켓 2개인 NUMA 환경에서 이사 잘못 가면 메모리 읽다 10배 느려짐 | **NUMA-aware 도메인 밸런싱**으로 같은 소켓 안에서만 훔치게 막음 | 원격 메모리 찌르는 걸 차단해서 NUMA 병목 원천 봉쇄 |

#### 한줄 요약

- 부하 불균형은 훔치기로 잡고, 잦은 이사로 생기는 캐시 폭망은 taskset 핀셋으로 묶어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **멀티프로세서 스케줄링 선택 기준(Multiprocessor Scheduling Criteria)**: 코어 수가 몇 개인지, 캐시가 중요한 작업인지, 락 경합이 터지는지 각 재서 MQMS를 세팅하는 잣대이다.

</details>

- **멀티프로세서 스케줄링 선택 기준** 원칙에 따라, 쌍팔년도 투코어는 **SQMS**, 현대 수십/수백 코어 리눅스 생태계는 묻지도 따지지도 않고 **MQMS** 채택 기조 확립함

#### 한줄 요약

- 쌍팔년도 투코어 시절엔 SQMS가 먹혔지만, 코어 넘쳐나는 지금은 무조건 MQMS로 간다.
