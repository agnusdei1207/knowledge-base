## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SQMS(Single-Queue Multiprocessor Scheduling)**: 모든 CPU 코어가 단일 전역 런 큐(Global Run Queue)를 공유하여 스케줄링하는 방식.
- **MQMS(Multi-Queue Multiprocessor Scheduling)**: 각 CPU 코어마다 독립된 로컬 런 큐를 유지하고 작업 훔치기(Work Stealing)로 균형을 맞추는 방식.

</details>

- 정의/개념: 단일 큐 공유(SQMS)의 락 병목을 극복하기 위해 **코어별 독립 로컬 큐와 작업 훔치기(Work Stealing)** 를 적용하는 다중 프로세서 스케줄링
- 배경/필요성: 멀티코어 환경에서 단일 전역 큐(SQMS)의 전역 락 경합($O(N)$) 및 **잦은 프로세스 코어 이동에 따른 L1/L2 캐시 친화도 파괴 한계**

#### 한줄 요약
- 단일 전역 큐(SQMS)의 락 병목을 코어별 다중 큐(MQMS)와 작업 훔치기로 해결한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **캐시 친화도(Cache Affinity)**: 프로세스가 직전에 실행되었던 동일 CPU 코어에서 다시 실행될 때 L1/L2 캐시 적중률이 극대화되는 성질.
- **작업 훔치기(Work Stealing)**: 자신의 로컬 큐가 비어 유휴 상태가 된 코어가 바쁜 다른 코어의 큐 꼬리에서 작업을 가져와 실행하는 부하 분산.

</details>

- **SQMS**: 단일 큐 기반으로 자연스러운 부하 균형이 가능하나 **락 경합(Lock Contention)** 으로 코어 확장 한계
- **MQMS**: 코어별 로컬 큐로 락 경합을 제거하고 **캐시 친화도(Cache Affinity)** 를 보존하여 선형적 확장성 확보
- MQMS의 코어 간 작업 불균형은 **작업 훔치기(Work Stealing)** 알고리즘을 통해 해소

#### 한줄 요약
- SQMS는 구현이 단순하나 락 병목이 있고, MQMS는 캐시 친화도와 확장성이 우수하다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **로드 밸런서(Load Balancer)**: 리눅스 커널에서 주기적으로 스케줄링 도메인 계층을 순회하며 코어 간 런 큐 부하를 측정하고 프로세스를 이주시키는 모듈.

</details>

```text
[다중 프로세서 스케줄링 체계]
  │
  ├─ [단일 큐 모델 SQMS] (중앙 집중식 분배)
  │     ├─ [글로벌 런 큐] (단일 전역 락 보호)
  │     └─ [단일 큐 단점] (락 경합 및 캐시 미스)
  │
  └─ [다중 큐 모델 MQMS] (코어별 분산 큐)
        ├─ [코어별 로컬 큐] (독립 락·캐시 친화도 보존)
        ├─ [작업 훔치기 엔진] (Work Stealing 유휴 훔침)
        └─ [스케줄링 도메인] (계층적 로드 밸런서)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 글로벌 런 큐 | 작업의 **중앙 집중식 분배** |
| 로컬 런 큐 | 코어별 디스패치와 **캐시 친화도 보존** |
| 작업 훔치기 엔진 | 유휴 코어의 **부하 균형 조정** |
| 스케줄링 도메인 | SMT·코어·NUMA의 **계층적 분산** |

#### 한줄 요약
- 큐의 개수가 곧 락의 범위이므로, 중앙 큐는 완벽한 부하 균형을 락 경합으로, 분산 큐는 무경합을 불균형과 작업 훔치기 비용으로 지불한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Push vs Pull 마이그레이션**: 과부하 코어가 작업을 밀어내는 Push와 유휴 코어가 작업을 당겨오는 Pull 부하 분산 방식.

</details>

```text
1. SQMS 디스패치 흐름
   [CPU 코어] ──(전역 큐 스핀락 획득 시도)──► [락 경합 대기 지연] ──► [작업 인출]
                                                                        │
   (이전과 다른 코어에 배정되어 L1/L2 캐시 콜드 미스 발생) ◄───────────┘

2. MQMS 디스패치 흐름 (Linux CFS)
   [CPU 코어] ──(자신의 로컬 큐 직접 접근)──► [락 경합 0, 즉각 디스패치 실행]
                                                      │ (L1/L2 캐시 웜 히트)
   로컬 큐가 비어 유휴 상태가 되었는가? ◄────────────┘
   ┌────┴─────┐
  예           아니오 (로컬 큐 작업 계속 실행)
   │
타 코어의 로컬 큐를 스캔하여 작업 훔치기(Work Stealing) 수행
```

#### 한줄 요약
- SQMS는 매 인출마다 전역 락 대기를 치르고 MQMS는 로컬 큐가 빌 때만 훔치기 비용을 치르므로, 코어 수가 늘수록 상시 비용과 간헐 비용의 차이가 벌어진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **선형 확장성(Linear Scalability)**: 코어 수가 4개에서 64개, 128개로 증가할 때 처리량이 락 병목 없이 정비례하여 증가하는 성질.

</details>

| 비교 항목 | SQMS (단일 큐 스케줄러) | MQMS (다중 큐 스케줄러) |
|:---|:---|:---|
| 락 경합 수준 | **코어 수 비례 락 경합 폭증 ($O(N)$)** | **락 경합 전무 (코어별 로컬 락)** |
| 캐시 친화도 | **불량 (프로세스가 매번 다른 코어로 이동)** | **최상 (동일 코어 지속 실행으로 캐시 보존)** |
| 부하 균형성 | 자연스러운 완전 균형 | 작업 훔치기(Work Stealing) 오버헤드 필요 |
| 확장성 한계 | 4~8코어 이상에서 성능 역전 | **수백 코어까지 선형적 확장(Linear Scaling)** |
| 현대 채택 현황 | 교육용/단순 RTOS | **현대 범용 OS 표준 (Linux CFS, Windows)** |

#### 한줄 요약
- 소수 코어는 SQMS가 단순하나, 대규모 멀티코어 서버는 MQMS가 필수적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 어피니티(taskset)**: 성능에 민감한 스레드를 특정 CPU 코어에 고정(Pinning)하여 코어 간 마이그레이션을 금지하는 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| MQMS에서 특정 코어에만 작업이 몰려 유휴 코어 발생 | **Work Stealing 주기 튜닝 및 계층적 로드 밸런싱** | 코어 간 CPU 이용률 95% 균일 분배 |
| 잦은 작업 훔치기로 인한 캐시 무효화 오버헤드 | **마이그레이션 비용 임계값(`migration_cost_ns`)** 설정 | 짧은 유휴 시 섣부른 작업 이동 차단 |
| 극초저지연 금융 트랜잭션의 캐시 미스 방지 | **`taskset / pthread_setaffinity_np` 코어 고정** | 코어 이동 0화 및 L1/L2 캐시 적중률 99% 달성 |
| NUMA 노드 간 무분별한 작업 이동으로 버스 병목 | **NUMA-Aware 스케줄링 도메인 격리** | 동일 소켓 내부에서만 작업 훔치기 우선 수행 |

#### 한줄 요약
- 큐를 코어별로 나누면 락 경합과 캐시 손실은 사라지지만 부하 불균형이 새로 생기므로, 작업 훔치기 빈도와 마이그레이션 비용 임계로 균형과 친화도 중 어디에 무게를 둘지 조정한다.

## Ⅶ. 결론

- 현대 멀티코어/대칭형 다중처리(SMP) 운영체제(Linux CFS/EEVDF, Windows)의 **표준 스케줄러 아키텍처**로 확립되었으며, 실무 고성능 환경에서는 **코어별 독립 로컬 큐와 계층적 도메인 로드 밸런싱을 기본으로, 불필요한 캐시 무효화를 막는 `migration_cost_ns` 튜닝, 초저지연 핵심 스레드의 CPU 어피니티(`taskset`) 고정, NUMA 노드 경계를 준수하는 작업 훔치기**를 결합하여 처리량을 극대화

#### 한줄 요약
- MQMS는 분산 큐와 작업 훔치기 기법을 통해 락 병목을 없애고 멀티코어의 물리적 연산 잠재력을 100% 발휘하게 하는 핵심 스케줄링 기술이다.
