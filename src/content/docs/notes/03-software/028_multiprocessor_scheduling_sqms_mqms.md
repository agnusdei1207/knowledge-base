## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다중 프로세서 스케줄링(Multiprocessor Scheduling)**: 복수의 CPU 코어에 프로세스·스레드를 효율적으로 배분하여 코어 이용률·캐시 효율·부하 균형을 최적화하는 스케줄링 기법.
- **SQMS(Single Queue Multiprocessor Scheduling)**: 모든 CPU 코어가 단일 전역 실행 큐를 공유하고 동기화 잠금을 경쟁하여 작업을 획득하는 단순 스케줄링 방식.
- **MQMS(Multi-Queue Multiprocessor Scheduling)**: CPU 코어별로 독립 로컬 큐를 보유하고 작업 훔치기(Work Stealing)로 코어 간 부하를 분산하는 확장형 스케줄링 방식.

</details>

- 정의/개념: 멀티코어 환경에서 단일 전역 큐의 잠금 경합을 수반하는 **SQMS**와 코어별 로컬 큐로 캐시 친화도·확장성을 확보하는 **MQMS** 비교
- 배경/필요성: 코어 수 증가에 따라 단일 큐 잠금 경합이 선형 확장을 저해하므로, **코어별 큐 분리 및 동적 부하 분산 체계 필수**

#### 한줄 요약

- 단일 전역 큐의 잠금 경합 한계를 극복하기 위해 코어별 로컬 큐와 작업 훔치기를 적용하는 MQMS

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **캐시 친화도(Cache Affinity)**: 프로세스를 이전에 실행한 코어의 L1/L2 캐시에 이미 데이터가 적재되어 있어 동일 코어에 재배정 시 캐시 적중률이 높은 특성.
- **작업 훔치기(Work Stealing)**: MQMS에서 로컬 큐가 빈 유휴 코어가 부하가 높은 코어의 로컬 큐에서 작업을 가져와 균형을 맞추는 동적 부하 분산 기법.

</details>

- **SQMS**: 단일 전역 큐의 구현 단순성, 코어 수 증가에 따른 **잠금 경합(Lock Contention)** 확대
- **MQMS**: 코어별 로컬 큐로 **캐시 친화도** 보존·잠금 경합 제거, **작업 훔치기**로 부하 균형 유지
- 코어 간 부하 불균형 감지·조정 비용이 MQMS의 운영 오버헤드

#### 한줄 요약

- SQMS는 구현 단순하나 잠금 병목, MQMS는 캐시 친화도와 확장성이 높으나 부하 균형 관리 필요

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **잠금 경합(Lock Contention)**: SQMS에서 다수의 CPU 코어가 전역 큐 접근 잠금을 동시에 획득하려 할 때 대기하며 발생하는 성능 병목.

</details>

```text
[ SQMS vs MQMS 구조 ]
SQMS (단일 전역 큐)          MQMS (코어별 로컬 큐)
┌────────────────┐             [CPU 0 큐] [CPU 1 큐]
│  전역 실행 큐  │              │                │
│ (잠금 경합 발생)│              │  작업 훔치기   │
└───┬────┬────┬──┘              │◄──────────────►│
    ▼    ▼    ▼                 ▼                ▼
[CPU0][CPU1][CPU2]           [CPU 0]         [CPU 1]
(캐시 친화도 보장 어려움)    (캐시 유지, 잠금 경합 없음)
```

선의 의미: SQMS의 전역 큐와 CPU 간 연결은 잠금 경합 발생 경로, MQMS의 양방향 화살표는 작업 훔치기 부하 분산 관계

| 구성요소 | 책임 |
|:---|:---|
| **전역 실행 큐 (SQMS)** | 모든 코어가 공유하는 단일 작업 대기열 (잠금 경합의 근원) |
| **코어별 로컬 큐 (MQMS)** | 코어 전용 작업 대기열로 잠금 없이 고속 디스패치 |
| CPU 코어 집합 | 큐에서 추출한 작업을 실행 |
| 부하 분산기 | 코어 간 큐 길이 불균형 감지 시 **작업 훔치기** 수행 |

#### 한줄 요약

- SQMS는 전역 큐 잠금 경합으로 성능이 제한되고, MQMS는 로컬 큐로 고속 디스패치하며 작업 훔치기로 균형을 유지

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Push/Pull 마이그레이션**: 부하 과다 코어가 작업을 타 코어로 이전(Push)하거나, 유휴 코어가 타 코어에서 작업을 가져오는(Pull) 부하 분산 방식.

</details>

```text
[ SQMS 실행 경로 ]              [ MQMS 실행 경로 ]
전역 큐 잠금 획득 대기           코어별 로컬 큐 직접 접근
   │                                    │
   ▼ 잠금 획득                          ▼ 잠금 없이 디스패치
작업 선택·CPU 배정                 로컬 큐에서 작업 선택 (캐시 친화도 유지)
(캐시 미스 가능)                        │
                                        ▼ 로컬 큐 소진 시
                                   부하 불균형 탐지
                                        │
                                        ▼
                                   작업 훔치기 (타 코어 큐 Pull)
```

**동작 원리**

1. **SQMS 디스패치**: 전역 큐에 잠금을 획득한 코어가 작업을 추출하여 실행 (코어 이동으로 캐시 미스 가능)
2. **MQMS 로컬 디스패치**: 코어가 자신의 로컬 큐에서 잠금 없이 작업을 직접 추출하여 실행 (캐시 친화도 유지)
3. **작업 훔치기**: 로컬 큐가 빈 유휴 코어가 부하 과다 코어의 큐에서 작업을 Pull하여 균형 확보

#### 한줄 요약

- SQMS는 전역 큐 잠금으로 직렬화되고, MQMS는 로컬 큐로 병렬 디스패치하며 작업 훔치기로 부하를 균형화

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Linux CFS 다중 큐**: 리눅스 CFS 스케줄러가 코어별 `cfs_rq`를 유지하고 `load_balance` 함수로 주기적 작업 훔치기를 수행하는 MQMS 구현체.

</details>

| 비교 항목 | SQMS (단일 큐) | MQMS (다중 큐) |
|:---|:---|:---|
| 적용 기준 | 소수 코어·구현 단순성 우선 환경 | 다수 코어·고확장성·캐시 효율 우선 환경 |
| 핵심 특징 | 전역 큐 공유·구현 단순, 자연 부하 균형 | 코어별 독립 큐·**캐시 친화도** 유지·선형 확장 |
| 한계 및 위험 | 코어 수 증가에 따른 **잠금 경합** 선형 확대 | 부하 불균형 감지·**작업 훔치기** 관리 오버헤드 |

#### 한줄 요약

- 소수 코어 단순 환경은 SQMS, 다수 코어 고확장성 환경은 MQMS 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 어피니티(CPU Affinity, taskset)**: 특정 프로세스·스레드를 지정 코어에 고정하여 코어 이동에 의한 캐시 미스를 방지하는 커널 스케줄링 제어 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 코어 간 작업량 편차로 일부 코어 유휴 발생 | **작업 훔치기(Work Stealing)** 주기적 수행 | 코어 전체 이용률 균형 유지 |
| 잦은 코어 이동으로 **캐시 친화도** 저하 | **CPU 어피니티(taskset)** 로 성능 민감 프로세스를 특정 코어에 고정 | L1/L2 캐시 적중률 향상·캐시 미스 감소 |
| NUMA 다중 소켓 환경에서 원격 메모리 접근으로 성능 저하 | **NUMA-aware 도메인 밸런싱**으로 동일 소켓 코어 간 작업 훔치기 제한 | 원격 메모리 접근 최소화로 NUMA 병목 방지 |

#### 한줄 요약

- 부하 불균형은 작업 훔치기로, 캐시 미스는 CPU 어피니티로, NUMA 병목은 도메인 밸런싱으로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **멀티프로세서 스케줄링 선택 기준**: 코어 수·캐시 민감도·확장성 요구·NUMA 환경 여부에 따라 SQMS와 MQMS를 결정하는 판단 기준.

</details>

- 소수 코어 환경은 **SQMS**, 다수 코어·고확장성·캐시 민감 환경은 **MQMS(Linux CFS 다중 큐)** 선택

#### 한줄 요약

- 다수 코어·고확장성 현대 시스템에서는 MQMS와 작업 훔치기 기반 동적 부하 균형을 표준으로 적용
