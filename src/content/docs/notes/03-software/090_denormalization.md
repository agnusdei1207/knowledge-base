## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **반정규화(Denormalization)**: 측정된 조회 병목을 줄이기 위해 데이터 중복•테이블 통합•사전 집계를 의도적으로 도입하는 읽기 성능 최적화 설계 기법이다.
- **읽기 성능 최적화 설계**: 조회 경로의 조인•집계•입출력을 줄이도록 저장 구조를 바꾸는 설계이다.
- **95백분위 지연(95th-percentile Latency, p95)**: 요청 95%가 완료되는 지연 경계값이다.

</details>

- 정의/개념: **반정규화**는 측정된 조회 병목을 줄이기 위해 데이터 중복•테이블 통합•사전 집계를 의도적으로 도입하는 **읽기 성능 최적화 설계**이다.
- 배경/필요성: 정규화 구조의 반복 조인•집계로 **95백분위 지연** 목표를 초과할 수 있다.

#### 한줄 요약

- 자주 찾는 내용을 미리 복사해 두고 원본이 바뀔 때 복사본도 맞추는 방식이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **조회 단축**: 조인•집계와 디스크 접근을 줄여 읽기 응답시간을 낮추는 효과이다.
- **쓰기 증가**: 같은 사실을 여러 위치에 갱신하며 쓰기 작업과 실패 지점이 늘어나는 비용이다.
- **정합성 통제**: 원본과 복사본 사이의 지연•누락•불일치를 감시하고 복구하는 활동이다.

</details>

- **조회 단축**: 조인•집계와 디스크 접근 감소한다.
- **쓰기 증가**: 같은 사실을 여러 위치에 갱신한다.
- **정합성 통제**: 동기화 지연과 실패를 관리한다.

#### 한줄 요약

- 읽기는 빨라지지만 복사본이 늘어날수록 수정 누락을 막기 어려워진다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **기준 데이터(Source of Truth)**: 불일치 때 최종 판단에 사용하는 원본 값이다.
- **데이터 버전(Data Version)**: 원본 값의 변경 순서를 나타내는 정보이다.
- **변경 식별자(Change Identifier)**: 원본 변경 사건을 구분하는 값이다.
- **이벤트 값(Event Value)**: 조회 모델에 전달할 원본 변경 내용이다.
- **반정규화 데이터**: 읽기 패턴에 맞춰 중복•통합•요약해 저장한 조회 모델이다.
- **원본 차이(Source Difference)**: 원본과 조회 모델의 값 불일치이다.
- **동기화 지연(Synchronization Lag)**: 원본 변경이 조회 모델에 반영되기까지의 시간이다.
- **중복•통합•요약 구조**: 조회 패턴에 맞춰 복제하거나 합치거나 미리 계산한 저장 형태이다.

</details>

```text
[원본 저장소]
      |
[변경 이벤트]
      |
[동기화 처리기]
      |
[조회 모델]
      |
[정합성 검증기]
      |
      +------ [원본 저장소와 비교]
```

선의 의미: 원본 변경은 이벤트와 처리기를 거쳐 조회 모델에 반영되며, 검증기는 원본과 조회 모델의 차이와 지연을 확인한다.

| 구성요소 | 책임 |
|:---|:---|
| 원본 저장소 | 정규화된 **기준 데이터•버전** 관리 |
| 변경 이벤트 | **변경 식별자**•**데이터 버전**•**이벤트 값** 전달 |
| 동기화 처리기 | **중복•통합•요약 구조** 갱신 |
| 조회 모델 | 읽기용 **반정규화 데이터** 저장 |
| 정합성 검증기 | **원본 차이•동기화 지연** 탐지 |

#### 한줄 요약

- 원본 변경을 조회용 복사본에 반영하고 차이와 지연을 검사한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **원본•이벤트 원자 기록**: 원본 변경과 발행 정보를 한 거래로 저장하는 단계이다.
- **변경 식별자•버전 수신**: 변경 사건과 적용 순서를 확인하는 단계이다.
- **최신 원본•파생값 계산**: 누락을 보완하고 조회용 값을 만드는 단계이다.
- **조회 모델 멱등 갱신**: 같은 이벤트의 중복 효과 없이 값을 반영하는 단계이다.
- **버전•동기화 지연 검증**: 불일치와 재처리 대상을 찾는 단계이다.

</details>

```text
원본 변경 명령
      |
      v
1. 원본•이벤트 원자 기록
      |
      v
2. 변경 식별자•버전 수신
      |
      v
3. 최신 원본•파생값 계산
      |
      v
4. 조회 모델 멱등 갱신
      |
      v
5. 버전•동기화 지연 검증
      |
      +-- 불일치 --> 재처리 대기열
      |
      +-- 일치 ----> 준비된 조회 결과
```

### 동작 원리

- **1. 원본•이벤트 원자 기록**: **원본•이벤트 원자 기록**으로 변경과 발행 정보를 함께 저장한다.
- **2. 변경 식별자•버전 수신**: **변경 식별자•버전 수신**으로 중복과 적용 순서를 확인한다.
- **3. 최신 원본•파생값 계산**: **최신 원본•파생값 계산**으로 조회용 중복•요약값을 생성한다.
- **4. 조회 모델 멱등 갱신**: **조회 모델 멱등 갱신**으로 중복 효과 없이 버전을 반영한다.
- **5. 버전•동기화 지연 검증**: **버전•동기화 지연 검증**으로 불일치와 지연을 재처리한다.

> 요약: **원본•이벤트 원자 기록**과 **버전•동기화 지연 검증**으로 조회 모델 정합성을 관리한다.

#### 한줄 요약

- 원본을 먼저 고친 뒤 복사본을 갱신하고, 조회는 준비된 복사본에서 빠르게 처리한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **중복 컬럼(Duplicated Column)**: 조인을 줄이려고 다른 테이블의 속성값을 복제한 열이다.
- **요약 테이블(Summary Table)**: 반복 조회하는 집계 결과를 미리 저장한 테이블이다.
- **테이블 통합**: 상시 조인하는 관련 테이블을 하나의 구조로 합치는 반정규화 방식이다.
- **널(Null, NULL)**: 값이 없거나 알려지지 않았음을 나타내는 표시이다.
- **빈번한 속성 조인**: 여러 조회가 같은 속성을 얻기 위해 반복 수행하는 테이블 결합이다.
- **반복 집계 조회**: 같은 범위와 수식을 여러 요청에서 다시 계산하는 조회이다.
- **1:1•상시 조인**: 일대일 관계의 두 테이블을 대부분의 조회에서 함께 결합하는 패턴이다.
- **속성 복제**: 조인을 줄이기 위해 원본 속성값을 다른 테이블에 중복 저장하는 방식이다.
- **집계 결과 사전 저장**: 반복 계산을 피하려고 합계•건수 같은 결과를 미리 보관하는 방식이다.
- **관련 테이블 통합**: 항상 함께 조회하는 테이블을 한 저장 구조로 합치는 방식이다.
- **측정된 읽기 병목**: 실행 계획과 지연 및 입출력 수치로 확인한 조회 성능 제한 지점이다.
- **관리 가능한 중복**: 원본•동기화 책임•검증 절차가 명확한 중복 데이터이다.

</details>

| 반정규화 유형 | 중복 컬럼 | 요약 테이블 | 테이블 통합 |
|:---|:---|:---|:---|
| 적용 기준 | **빈번한 속성 조인** | **반복 집계 조회** | **1:1•상시 조인** |
| 핵심 특징 | **중복 컬럼**으로 **속성 복제** | **집계 결과 사전 저장** | **관련 테이블 통합** |
| 한계 | 속성 갱신 누락 | 최신성 지연 | 중복•**널** 증가 |

> 요약: **측정된 읽기 병목**에만 **관리 가능한 중복** 추가가 핵심이다.

#### 한줄 요약

- 이름•합계처럼 자주 쓰는 값을 미리 저장하면 빨라지지만 바뀔 때마다 함께 고쳐야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **실행 계획(Execution Plan)**: 데이터 중복 전후에 비교할 조회 경로이다.
- **95백분위 지연(95th-percentile Latency, p95 Latency)**: 요청 95%가 완료되는 지연 경계값이다.
- **입출력(Input/Output, I/O)**: 저장장치와 메모리 사이의 데이터 전송 작업이다.
- **단일 원본(Single Source of Truth)**: 불일치 때 기준이 되는 권위 있는 저장소이다.
- **소유권(Ownership)**: 원본 값을 변경할 책임 주체이다.
- **트랜잭셔널 아웃박스(Transactional Outbox)**: 원본 변경과 이벤트 기록을 한 거래로 묶는 방식이다.
- **멱등성(Idempotency)**: 이벤트 반복 처리의 중복 효과를 막는 성질이다.
- **허용 지연(Allowed Lag)**: 조회 모델이 원본보다 늦어도 되는 시간이다.
- **대기열 감시(Queue Monitoring)**: 미반영 이벤트 수와 체류 시간을 관찰하는 활동이다.
- **버전 검사(Version Check)**: 누락과 역순 이벤트를 판정하는 활동이다.
- **재처리(Reprocessing)**: 실패한 이벤트를 다시 적용하는 활동이다.
- **정합성 검증(Consistency Validation)**: 원본과 조회 모델의 값을 맞추는 활동이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전후 측정 없이 중복을 추가해 쓰기 비용만 증가 | **실행 계획**•**95백분위 지연**•**입출력** 전후 비교 | 효과 없는 중복 방지 |
| 여러 복사본을 원본으로 취급해 불일치 판정 불가 | **단일 원본•소유권** 명시 | 불일치 판정 기준 확보 |
| 원본 갱신과 이벤트 발행이 분리돼 일부 반영 | **트랜잭셔널 아웃박스•멱등성** 적용 | 일부 갱신•중복 반영 방지 |
| 허용 최신성을 정하지 않아 지연 장애 판단 불가 | **허용 지연•대기열 감시** | 동기화 지연 범위 통제 |
| 누락•역순 이벤트로 원본과 조회 모델이 불일치 | **버전 검사•재처리•정합성 검증** | 누락•순서 역전 복구 |

> 적용 사례: 대시보드의 일별 매출을 요약 테이블에 저장하고, 원본 주문과의 차이 및 동기화 지연을 함께 감시

#### 한줄 요약

- “얼마나 빨라졌는가”와 “얼마나 늦거나 틀릴 수 있는가”를 함께 측정해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **조회 이득(Read Benefit)**: 반정규화로 얻는 읽기 성능 개선이다.
- **동기화 비용(Synchronization Cost)**: 복사본 일관성을 관리하는 부담이다.
- **허용 최신성(Acceptable Freshness)**: 조회 모델의 지연을 허용하는 기준이다.
- **반정규화 적용 기준**: 조회 이득과 동기화 비용 및 허용 최신성을 함께 평가하는 선택 기준이다.

</details>

- **반정규화 적용 기준**에 따라 **조회 이득**이 **동기화 비용**보다 크고 **허용 최신성**을 지킬 때 적용한다.

#### 한줄 요약

- **반정규화 적용 기준**은 복사로 얻는 속도와 복사본 관리 부담을 함께 비교한다.
