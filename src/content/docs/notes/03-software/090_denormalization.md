## 미리 알고가기

- **반정규화(Denormalization)**: 조회 병목에 중복 컬럼·요약 테이블을 추가함
- **정규화(Normalization)**: 중복과 갱신 이상을 줄이는 논리 설계임
- **데이터베이스(Database, DB)**: 원본과 중복 데이터를 저장·관리함
- **입출력(Input/Output, I/O)**: 반정규화가 줄이려는 저장장치 접근임
- **95백분위 질의 지연(95th Percentile Query Latency, p95)**: 느린 상위 질의의 응답시간을 나타냄
- **동기화(Synchronization)**: 원본 변경을 중복 데이터에 반영함
- **적용 판단**: 조회 이득과 불일치 관리 비용을 비교함
- **조인(Join)**: 공통 값으로 여러 테이블의 행을 결합하는 연산임
- **집계(Aggregation)**: 여러 행을 합계·평균·건수 같은 요약값으로 계산하는 연산임
- **요약 테이블(Summary Table)**: 반복 조회하는 집계 결과를 미리 저장한 테이블임
- **이벤트 동기화(Event-driven Synchronization)**: 원본 변경 사건을 메시지로 전달해 중복 데이터를 갱신하는 방식임
- **배치(Batch)**: 데이터를 일정량이나 일정 시간 단위로 모아 처리하는 방식임
- **원본 데이터(Source of Truth)**: 불일치가 생겼을 때 최종 기준으로 삼는 권위 있는 데이터임

## Ⅰ. 개요

- 정의/개념: 통제된 중복 저장으로 **반복 조인·집계 비용**을 줄이는 설계
- 기존 한계: 고정된 정규화 구조는 **측정된 대량 조회 병목** 대응에 한계

### 쉽게 이해하기 (학습용)
- 자료를 한 장에 복사하되 원본이 바뀌면 함께 고치는 방식임

## Ⅱ. 특징

- 중복 저장이 조인·집계 연산을 줄여 조회 지연을 낮춘다.
- 중복 저장은 갱신 누락과 데이터 불일치를 키운다.
- 측정된 병목에만 적용해야 동기화 비용을 제한한다.

### 쉽게 이해하기 (학습용)
- 읽을 때는 빠르지만 같은 내용을 여러 곳에 적으므로 수정할 때 빠뜨릴 위험이 커짐

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 병목 질의 | 느린 조회·집계와 필요한 중복을 식별함 |
| 중복 구조 | 컬럼과 요약 테이블로 조인과 집계를 줄임 |
| 동기화 경로 | 이벤트와 배치로 원본과 맞춤 |
| 검증 지표 | 조회 지연과 불일치 건수를 함께 측정함 |

```text
  병목식별
      ↓
  중복선정
      ↓
  동기설계
      ↓
  검증측정
```

> 요약: 병목별 중복 구조와 원본 동기화를 함께 검증함

### 쉽게 이해하기 (학습용)
- 느린 화면에 필요한 복사본과 동기화 장치를 함께 둠

## Ⅳ. 원리 및 절차 흐름도

```text
  병목측정
      ↓
  중복선정
      ↓
  동기설계
      ↓
  효과검증
      ↓
  유지판정
```

| 절차 | 설명 |
|:---|:---|
| 병목측정 | 지연 분포로 조인과 집계 병목을 확인함 |
| 중복선정 | 변경이 가장 적은 중복 구조를 선택함 |
| 동기설계 | 허용 지연에 맞춰 갱신 경로를 설계함 |
| 효과검증 | 상위 지연과 불일치 건수를 측정함 |
| 유지판정 | 성능 이득과 정합성 비용을 비교함 |

> 요약: 최소 중복의 조회 이득과 정합성 비용을 비교함

### 쉽게 이해하기 (학습용)
- 느린 곳만 복사하고 속도와 내용 일치를 함께 확인함

## Ⅴ. 종류 및 비교

| 데이터 구조 | 반정규화 | 정규화 |
|:---|:---|:---|
| 적용 기준 | 측정된 조회 병목·**동기화 수단 확보** | 갱신 **무결성 우선** |
| 핵심 특징 | 조회 구조의 **통제된 중복 저장** | 동일 사실의 **단일 저장** |
| 한계 | 중복 불일치·**갱신 누락** | 조인 증가·**조회 지연** |

> 요약: 정규화는 갱신 무결성이고 반정규화는 조회 비용을 우선함

### 쉽게 이해하기 (학습용)
- 반정규화는 원본을 버리는 방식이 아니라 측정된 조회 병목을 줄이기 위해 관리 가능한 복사본을 추가하는 방식임

## Ⅵ. 실무 사례

1. 대시보드는 **요약 테이블·동기화 지연** 검증

### 쉽게 이해하기 (학습용)
- 대시보드는 집계 결과를 미리 저장하고 이벤트 지연을 측정해 빠른 조회와 최신성의 균형을 확인함

## Ⅶ. 결론

- **조회 이득**이 동기화·불일치 비용보다 클 때 제한 적용

### 쉽게 이해하기 (학습용)
- 반정규화는 원본·동기화·불일치 지표를 함께 갖추고 조회 이득이 관리 비용보다 클 때만 유지함
