## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Denormalization (반정규화 / 역정규화)**: 정규화된 데이터베이스 스키마에서 시스템의 읽기 성능(Read Throughput/Latency)을 향상시키기 위해, 의도적으로 데이터 중복을 허용하거나 테이블을 통합/분할/요약하는 데이터베이스 물리 아키텍처 최적화 기법.
- **Read-Heavy Workload**: 데이터의 CUD(Create/Update/Delete) 수정 빈도 대비 조회(Read) 쿼리 발생 비율이 8:2 이상으로 압도적으로 높은 시스템 부하 환경.
- **Trade-off in Denormalization**: 읽기 속도(Read Speed) 및 `JOIN` 비용 감소의 이득 대 데이터 중복성에 따른 쓰기(Write) 오버헤드, 저장공간 증가, 무결성 유지 난이도 증가 간의 상충 관계.

</details>

- 정의/개념: 정규화된 스키마의 빈번한 `JOIN` 연산 및 집계(Aggregation) 병목을 해소하기 위해 의도적으로 중복 속성을 허용하고 테이블을 재구성하는 읽기 성능 최적화 기법인 **Denormalization**
- 배경/필요성: 반복 조인•집계는 **읽기 지연•계산 비용** 증가 유발

#### 한줄 요약

- 자주 찾는 내용을 미리 복사해 두고 원본이 바뀔 때 복사본도 맞추는 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Controlled Redundancy (통제된 중복)**: 무질서한 중복이 아니라, 애플리케이션 트랜잭션 및 트리거/동기화 배치를 통해 무결성을 통제하며 관리하는 전략적 중복.
- **Single Source of Truth (SSOT)**: 반정규화 컬럼이 존재하더라도 비즈니스 정답 데이터의 원천이 어디인가를 명확히 지정해 놓는 원칙.

</details>

- **Read Speed (읽기 속도)** 극대화 대 **Write Overhead (쓰기 비용)** 증가의 Trade-off
- **Controlled Redundancy (통제된 중복)** 기반의 성능 개선
- **Single Source of Truth (SSOT)** 원본 데이터 식별 및 애플리케이션 정합성 동기화 필수

#### 한줄 요약

- 읽기는 빨라지지만 복사본이 늘어날수록 수정 누락을 막기 어려워진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Duplicated Column**: 잦은 조인 대상 속성(예: 주문 테이블에 고객명 중복 저장)을 튜플 내에 직접 포함.
- **Summary Table**: 월별/일별 매출 집계 등 대용량 집계 결과를 사전에 계산해 저장하는 요약 테이블.
- **Table Partitioning / Merging**: 1:1 관계의 테이블을 1개로 합치거나(Merging), 1개의 거대 테이블을 범위/목적별로 쪼갬(Partitioning).

</details>

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        Denormalization 3대 기법                        │
├─────────────────────┬───────────────────┬──────────────────────────────┤
│ 1. 테이블 반정규화  │ 2. 속성 반정규화  │ 3. 관계 반정규화            │
├─────────────────────┼───────────────────┼──────────────────────────────┤
│ • 테이블 병합       │ • 중복 칼럼 추가  │ • 중복 관계 추가             │
│   (1:1, 1:N 통합)   │ • 파생 칼럼 추가  │   (다단계 조인 경로 단축)    │
│ • 테이블 분할       │   (합계, 평균 계산)│                              │
│   (수직/수평 분할)  │ • 이력 테이블 칼럼│                              │
│ • 요약 테이블 생성  │   추가            │                              │
└─────────────────────┴───────────────────┴──────────────────────────────┘
```

선의 의미: 반정규화의 적용 대상을 테이블 레벨, 속성(컬럼) 레벨, 관계(FK 경로) 레벨 3가지 관점으로 분류하는 아키텍처.

| 구분 (Category) | 적용 기법 (Technique) | 실무 적용 목적 및 사례 |
|:---|:---|:---|
| 테이블 반정규화 | **Table Merging, Partitioning, Summary Table** | 1:1 관계 테이블을 1개로 병합하여 조인 0화, 월별 매출 요약표 사전 생성 |
| 속성 반정규화 | **Duplicated Column, Derived Column** | 주문 테이블에 고객 이름 중복 저장, 장바구니에 총결제금액 파생 컬럼 미리 저장 |
| 관계 반정규화 | **Redundant Foreign Key (중복 FK)** | A $\rightarrow$ B $\rightarrow$ C 3단계 조인을 A $\rightarrow$ C 직접 참조 FK 추가로 단축 |

#### 한줄 요약

- 원본 변경을 조회용 복사본에 반영하고 차이와 지연을 검사한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Denormalization Decision Flow**: 1. 정규화 완비 $\rightarrow$ 2. 성능 측정 및 병목 확인 $\rightarrow$ 3. 대체 수단(인덱스, 캐시) 검토 $\rightarrow$ 4. 반정규화 적용 $\rightarrow$ 5. 정합성 검증.

</details>

```text
[정규화된 원본 모델]
               │
               ▼
[1. 읽기 병목 측정]
               │
               ▼ (인덱스/쿼리 튜닝으로 해결 가능한가?)
         ├── YES ──► [2. 인덱스•쿼리•캐시 적용]
         │
         └── NO
               ▼
[3. 반정규화 기법 적용]
               │
               ▼
[4. 동기화•복구 경로 구성]
               │
               ▼
[5. 성능•정합성 지표 검증]
```

### 동작 원리

1. 읽기 병목 측정: 느린 질의와 APM으로 비용 경로 확인.
2. 인덱스•쿼리•캐시 적용: 중복 없는 대안을 먼저 검증.
3. 반정규화 기법 적용: 측정된 경로에 중복•요약 구조 추가.
4. 동기화•복구 경로 구성: 원본 변경과 재처리 절차 연결.
5. 성능•정합성 지표 검증: 지연 개선과 복제 지연•오류 비교.

#### 한줄 요약

- 원본을 먼저 고친 뒤 복사본을 갱신하고, 조회는 준비된 복사본에서 빠르게 처리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Normalization vs Denormalization**: 정규화는 데이터 중복 최소화 및 무결성(Write) 중심, 반정규화는 조인 최소화 및 응답 속도(Read) 중심.

</details>

| 비교 항목 | Normalization (정규화) | Denormalization (반정규화) |
|:---|:---|:---|
| 최적화 목표 | **데이터 중복 최소화 & CUD 무결성 보장** | **조회 쿼리 성능(Read Speed) 극대화** |
| 데이터 저장 구조| 테이블 수 증가 (분해 구조) | 테이블 통합 및 중복 컬럼 존재 구조 |
| `JOIN` 연산 | 분해 경계에 따라 조인 필요 | **핵심 조회 경로의 조인 수 감소** |
| CUD 쓰기 성능 | **우수 (단일 위치 갱신으로 이상 없음)** | **저하 (중복 컬럼 연쇄 갱신 오버헤드)** |
| 적합 도메인 | **OLTP (금융 이체, 주문 결제 시스템)** | **OLAP / Data Warehouse / Read-Heavy 서비스** |

#### 한줄 요약

- 이름•합계처럼 자주 쓰는 값을 미리 저장하면 빨라지지만 바뀔 때마다 함께 고쳐야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Consistency Maintenance (정합성 유지 대책)**: 중복 컬럼의 데이터가 원본과 달라지지 않도록 DB Trigger, Batch Reconciliation, 또는 Spring Event 기반의 동기화 연동 체계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중복 컬럼 업데이트 누락으로 인한 데이터 불일치 | **Spring Application Event 또는 DB Trigger 기반 연쇄 갱신**| 정합성 보존 |
| 습관적 사전 반정규화로 인한 DB 스키마 난잡화 | **반정규화 전 Redis 캐시(In-Memory Cache) 도입 우선 검토** | 스키마 단순성 보존 |
| 파생 컬럼 계산 오류로 인한 수치 파행 | **매일 야간 데이터 정합성 검증 배치 프로그램(Reconciliation Batch) 가동**| 데이터 정확성 인가 |

> 사례: **배달의민족 / 쿠팡 주문 내역 내 가게 이름 및 상품명 속성 중복 저장**

#### 한줄 요약

- “얼마나 빨라졌는가”와 “얼마나 늦거나 틀릴 수 있는가”를 함께 측정해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **반정규화 수립 기준(Denormalization Standards)**: Read/Write 트래픽 비율, p95 쿼리 지연 시간 및 데이터 정합성 유지 비용에 의거한 체계.

</details>

- 측정 병목이 남으면 **통제된 반정규화**, 아니면 **정규화 모델 유지**

#### 한줄 요약

- 반정규화 적용 기준은 복사로 얻는 속도와 복사본 관리 부담을 함께 비교한다.
