## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **반정규화(Denormalization)**: 정규화된 데이터 모델에서 시스템 성능 향상과 조회 편의를 위해 의도적으로 중복, 통합, 분할을 수행하는 물리적 설계 기법.
- **Controlled Redundancy(통제된 중복)**: 무분별한 복사가 아닌, 동기화 메커니즘을 갖추고 정합성을 통제하는 전략적 데이터 중복.

</details>

- 정의/개념: 다중 조인 및 집계 연산의 성능 병목을 해소하기 위해 **테이블 병합, 중복·파생 컬럼 추가, 관계 단축 등 의도적으로 중복을 허용**하는 물리 모델링 기법
- 배경/필요성: 정규화 모델의 과도한 다단계 조인(Join) 및 **대규모 집계 연산에 따른 디스크 I/O 병목과 대용량 조회 응답 지연 심화 한계**

#### 한줄 요약
- 반정규화는 읽기 비용을 쓰기 시점의 동기화 비용으로 옮기는 거래이므로, 조회 대비 갱신 비율이 높은 테이블에서는 얻는 성능보다 정합성 관리 부담이 커진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Read vs Write Trade-off**: Join 감소로 조회(Read) 성능은 대폭 향상되나, 중복 컬럼 갱신(Write) 비용과 디스크 공간 소모가 증가하는 상충 관계.
- **SSOT(Single Source of Truth)**: 원본 데이터가 위치한 원천 테이블을 명확히 지정하여 중복 데이터와의 정합성 동기화 기준을 확립.

</details>

- 읽기 속도(Read Speed) 극대화 대 쓰기 오버헤드(Write Overhead) 증가의 **명확한 트레이드오프**
- 원본 데이터(SSOT)를 정의하고 동기화 경로를 수립하는 **통제된 중복(Controlled Redundancy)**
- 인덱스 튜닝 및 캐싱으로 해결되지 않는 병목에 적용하는 **물리적 데이터베이스 최후의 최적화 수단**

#### 한줄 요약
- 조인을 줄이고 사전 집계를 통해 읽기 성능을 높이되, 쓰기 정합성 관리 비용을 감수한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **반정규화 3대 영역**: 테이블 반정규화(병합/분할/집계), 속성 반정규화(중복/파생/이력 컬럼), 관계 반정규화(중복 FK 경로 단축).

</details>

```text
[반정규화 구성]
|-- 테이블 반정규화
|-- 속성 반정규화
|-- 관계 반정규화
|-- 동기화 엔진
```

선의 의미: 반정규화 대상과 중복 데이터 정합성 관리 구성

| 구성요소 | 책임 |
|:---|:---|
| 테이블 반정규화 | **병합·분할·집계표**로 조인·집계 비용 절감 |
| 속성 반정규화 | **중복·파생 컬럼**으로 단일 테이블 조회 지원 |
| 관계 반정규화 | **중복 FK**로 다단계 조인 경로 단축 |
| 동기화 엔진 | **이벤트·CDC·대사 배치**로 중복 정합성 유지 |

#### 한줄 요약
- 어느 차원에서 중복을 허용하든 원본과 사본이 갈라지는 지점이 반드시 생기므로, 반정규화의 실제 난이도는 중복을 만드는 일이 아니라 두 값을 언제 어떤 비용으로 맞출지 정하는 데 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **반정규화 의사결정 5단계**: 정규화 완료 $\to$ 병목 분석 $\to$ 대체 수단(인덱스/캐시) 검토 $\to$ 반정규화 적용 $\to$ 정합성 동기화 설계.

</details>

```text
3NF / BCNF 기반 정규화 데이터 모델 완성
        │
   [병목 식별] APM 및 슬로우 쿼리 로그에서 다중 Join 및 대규모 집계 지연 발견
        │
   인덱스 추가, 쿼리 튜닝, Redis 캐싱으로 성능 목표를 달성할 수 있는가?
   ┌────┴───────────────────────────┐
  예 (대체 수단으로 해결)           아니오 (반정규화 필수)
   │                                 │
인덱스/캐시 적용 완료              [반정규화 적용] 중복 컬럼(customer_name) 또는 일별 요약 테이블 생성
                                     │
                                  [동기화 경로 구축] 원본 수정 시 이벤트 발행 및 야간 정합성 대사 배치
                                     │
                                  성능 및 데이터 일관성 검증 완료
```

#### 한줄 요약
- 인덱스와 캐시는 원본을 그대로 둔 채 접근 경로만 바꿔 언제든 되돌릴 수 있지만 반정규화는 모델 자체를 바꿔 복구 비용이 크므로, 값싼 수단을 모두 소진한 뒤에 꺼내는 것이 순서다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정규화 vs 반정규화 비교**: 쓰기 정합성을 우선하는 정규화와 읽기 속도를 우선하는 반정규화의 트레이드오프.

</details>

| 비교 항목 | 정규화 (Normalization) | 반정규화 (Denormalization) |
|:---|:---|:---|
| 핵심 목적 | **데이터 중복 제거 및 이상 현상 방지** | **조인 연산 제거 및 조회 성능 극대화** |
| 읽기(Read) 성능 | 다단계 조인 발생으로 상대적 느림 | **단일 테이블/사전 집계로 초고속 조회** |
| 쓰기(Write) 오버헤드 | 단일 행만 수정 (오버헤드 최소) | **중복/파생 컬럼 연쇄 갱신 오버헤드 발생** |
| 데이터 정합성 | DBMS 엔진이 100% 무결성 보장 | **애플리케이션/배치 동기화 관리 부담 수반** |

#### 한줄 요약
- 정규화는 데이터 무결성을, 반정규화는 읽기 처리량을 우선하므로 비즈니스에 맞춰 절충한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Reconciliation Batch(정합성 대사 배치)**: 원본 데이터와 반정규화된 중복 데이터 간의 불일치를 매일 새벽 전수 검사하여 자동 보정하는 프로그램.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 원본 수정 시 중복 컬럼 갱신 누락으로 인한 데이터 불일치 | **Spring Application Event 또는 트랜잭션 내 연쇄 업데이트** | 원본-중복 데이터 간 실시간 정합성 보장 |
| 무분별한 반정규화로 인한 스키마 복잡도 폭증 | **반정규화 전 Redis 캐시 및 커버링 인덱스 최우선 검토** | 불필요한 스키마 변형 억제 |
| 파생 통계 수치 오차 누적으로 정산 오류 발생 | **야간 정합성 검증 대사 배치(Reconciliation Batch) 가동** | 누적 오차 0화 및 자동 자가 치유 |
| 요약 테이블 실시간 집계 부하 | **CQRS 패턴을 적용하여 Kafka 이벤트 기반 비동기 프로젝션** | 메인 트랜잭션 응답 지연 원천 차단 |

#### 한줄 요약
- 이벤트 동기화, 캐시 우선 검토, 정기 대사 배치, CQRS 비동기 프로젝션으로 무결성을 지킨다.

## Ⅶ. 결론

- 엔터프라이즈 대용량 데이터베이스 물리 모델링 및 성능 튜닝의 **핵심 트레이드오프(Read vs Write) 최적화 기법**으로 확립되었으며, 실무 적용 시에는 **반정규화에 앞서 인덱스 튜닝 및 Redis 캐싱 계층 도입을 최우선 검토하고, 불가피하게 중복 데이터를 도입할 경우 명확한 원본(SSOT) 정의, Kafka/CDC 기반의 실시간 이벤트 동기화, 야간 정합성 대사 배치(Reconciliation Batch)를 결합**하여 데이터 불일치 위험을 완벽히 통제

#### 한줄 요약
- 반정규화는 인덱스와 캐시로 해결되지 않는 병목을 극복하기 위해 통제된 중복을 허용하는 물리 데이터 모델링의 핵심 최적화 기법이다.
