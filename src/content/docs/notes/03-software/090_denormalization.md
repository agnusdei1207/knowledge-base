## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **반정규화 3대 기법**: 테이블 병합/분할/요약(테이블 레벨), 중복/파생 컬럼 추가(속성 레벨), 중복 관계 추가(관계 레벨)로 구성된 물리 모델링 최적화 기법.
- **다단계 JOIN 병목 및 응답 지연(Join Bottleneck & Latency)**: 과도하게 분해된 릴레이션을 매번 조인하거나 실시간 대용량 집계를 수행하여 디스크 I/O가 급증하고 시스템 처리량이 급락하는 문제.

</details>

- 정의/개념: 다중 조인 및 대용량 집계에 따른 쿼리 지연을 해소하기 위해 **테이블 병합, 중복·파생 컬럼 추가, 중복 관계 생성** 등 의도적으로 중복을 허용하는 물리 모델링 최적화 기법
- 배경/필요성: 고빈도 대용량 읽기 환경에서 정규화로 인한 **다단계 JOIN 연산 병목, 디스크 I/O 급증 및 사용자 응답 지연 위험** 직면

#### 한줄 요약

- 읽기 성능 향상을 위해 테이블, 속성, 관계 수준에서 의도적 중복을 허용하고 무결성을 통제

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **통제된 중복(Controlled Redundancy)**: 무질서한 데이터 복제가 아닌 애플리케이션 트랜잭션, 이벤트, 또는 동기화 배치를 통해 정합성을 보증하는 체계적 중복.
- **읽기/쓰기 상충(Read vs Write Trade-off)**: 조인 비용 감소로 읽기(Read) 속도는 극대화되나, 중복 데이터 갱신 비용 및 저장공간 부담(Write)이 증가하는 상충 관계.

</details>

- 읽기 속도(Read Speed) 극대화 대 쓰기 오버헤드(Write Overhead) 증가의 **명확한 트레이드오프**
- 원본 데이터(SSOT)를 명확히 정의하고 무결성을 유지하는 **통제된 중복(Controlled Redundancy)**
- 인덱스 및 캐시 튜닝으로 해결 불가한 병목에 적용하는 **물리적 스키마 최적화 수단** #### 한줄 요약

- 읽기 중심 워크로드에서 조인을 줄이고 사전 집계를 통해 성능을 극대화하되 정합성 관리 비용을 수반

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **요약/파생 테이블(Summary & Derived Table)**: 일별/월별 매출 합계, 주문 총액 등 실시간 연산 비용이 큰 집계 결과를 미리 계산하여 저장하는 테이블.

</details>

```text
[ 반정규화 3대 적용 영역 아키텍처 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      Denormalization 3대 적용 영역                      │
 ├─────────────────────┬───────────────────┬──────────────────────────────┤
 │ 1. 테이블 반정규화  │ 2. 속성 반정규화  │ 3. 관계 반정규화            │
 ├─────────────────────┼───────────────────┼──────────────────────────────┤
 │ • 1:1, 1:N 병합     │ • 중복 컬럼 추가  │ • 중복 FK 관계 추가          │
 │ • 수직/수평 분할    │   (고객명, 상품명)│   (다단계 조인 경로 단축)    │
 │ • 요약 테이블 생성  │ • 파생 컬럼 추가  │                              │
 │   (일별/월별 통계)  │   (총액, 잔액)    │                              │
 └─────────────────────┴───────────────────┴──────────────────────────────┘
```

선의 의미: 테이블 레벨, 속성(컬럼) 레벨, 관계(외래키 경로) 레벨의 3차원 반정규화 분류 체계.

| 구성요소 | 책임 |
|:---|:---|
| 테이블 반정규화 | 잦은 조인 대상 테이블 병합 및 대용량 분할, **사전 집계 요약 테이블 생성** |
| 속성 반정규화 | 조회 빈도가 높은 타 테이블 속성을 **중복 컬럼이나 연산 파생 컬럼으로 추가** |
| 관계 반정규화 | $A \rightarrow B \rightarrow C$ 조인 경로를 $A \rightarrow C$로 단축하기 위한 **중복 외래키(FK) 연결** |
| 정합성 동기화 엔진 | 원본(SSOT) 변경 시 중복 데이터를 갱신하는 **이벤트/트리거/배치 파이프라인** |

#### 한줄 요약

- 테이블, 속성, 관계의 3개 수준에서 반정규화를 적용하고 동기화 엔진으로 정합성을 보존

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **반정규화 5단계 절차**: 병목 식별 $\to$ 인덱스/캐시 우선 검토 $\to$ 반정규화 기법 선정 $\to$ 동기화 설계 $\to$ 성능/정합성 검증.

</details>

```text
[ 반정규화 결정 및 적용 5단계 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 정규화 모델 구축: 3NF/BCNF 완결    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 읽기 병목 측정: 슬로우 쿼리/APM분석 │
 └───────────────────┬────────────────────┘
                     │ (인덱스/캐시로 해결 불가 시)
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 반정규화 기법 적용: 테이블/속성/관계│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 동기화 경로 설계: 이벤트/배치 구축  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 성능 및 정합성 검증: TPS/지연 측정 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 정규화 모델 구축: 논리적 데이터 무결성을 위해 3NF/BCNF 정규화 모델을 먼저 완성.
2. 읽기 병목 측정: APM 및 슬로우 쿼리 로그를 통해 다중 조인 및 대용량 집계 병목을 식별.
3. 반정규화 기법 적용: 인덱스 튜닝 및 Redis 캐시로 해결되지 않을 경우 테이블 병합, 중복 컬럼, 파생 속성을 적용.
4. 동기화 경로 설계: 원본 데이터 변경 시 애플리케이션 이벤트나 DB 트리거, 야간 대사 배치를 통해 중복 데이터를 동기화.
5. 성능 및 정합성 검증: 조회 응답 시간 단축 효과와 쓰기 오버헤드 및 복제 지연을 종합 평가.

#### 한줄 요약

- 정규화 완비 $\to$ 병목 측정 $\to$ 반정규화 적용 $\to$ 동기화 구축 $\to$ 종합 검증의 5단계 절차

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정규화 vs 반정규화**: 데이터 무결성과 쓰기 최적화를 중시하는 정규화(Normalization)와 조회 처리량과 응답 속도를 중시하는 반정규화(Denormalization).

</details>

| 구분 | 정규화 (Normalization) | 반정규화 (Denormalization) |
|:---|:---|:---|
| **적용 기준** | 트랜잭션 무결성과 CUD 빈도가 높은 OLTP 환경 | 대규모 조회 트래픽 및 실시간 응답이 요구되는 환경 |
| **핵심 특징** | **중복 제거, 이상 현상 방지, 단일 위치 갱신** | **조인 감소, 사전 집계, 통제된 데이터 중복 허용** |
| **한계** | 복잡한 다중 조인 발생으로 읽기 응답 지연 | 중복 컬럼 갱신 오버헤드 및 데이터 불일치 위험 |

#### 한줄 요약

- 정규화는 데이터 무결성을, 반정규화는 읽기 성능을 우선시하므로 시스템 특성에 맞추어 절충

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 정합성 대사(Reconciliation Batch)**: 중복 또는 파생 컬럼의 값이 원본 데이터와 일치하는지 주기적으로 검증하고 보정하는 배치 프로그램.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중복 컬럼 갱신 누락으로 인한 데이터 불일치 | **Spring Application Event 또는 트랜잭션 내 연쇄 업데이트 적용** | 원본-중복 데이터 간 정합성 보장 |
| 무분별한 반정규화로 인한 스키마 복잡도 폭증 | **반정규화 적용 전 Redis 인메모리 캐시 및 인덱스 최적화 우선 검토** | 불필요한 스키마 변형 억제 |
| 파생 통계 수치 오차 누적으로 인한 정산 오류 | **야간 정합성 검증 대사 배치(Reconciliation Batch) 가동** | 누적 오차 자동 탐지 및 자가 치유 |

#### 한줄 요약

- 이벤트 기반 동기화, 캐시 우선 검토, 정기 대사 배치를 통해 데이터 무결성 훼손을 원천 방어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **적응형 데이터 아키텍처(Adaptive Data Architecture)**: 쓰기 영역은 정규화된 RDBMS로 처리하고 읽기 영역은 반정규화된 캐시/CQRS로 분리하는 아키텍처.

</details>

- **반정규화** 기반 맹목적인 기법이 아닌 철저한 성능 측정과 인덱스/캐시 튜닝 후 최후의 수단으로 적용해야 하는 공학적 타협점이며, 데이터 동기화와 대사 체계를 병행하여 무결성을 유지해야 함

#### 한줄 요약

- 정규화된 모델을 기반으로 조회 병목 지점에 통제된 중복을 선별 적용하여 성능과 정합성을 완성
