## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **인공지능 코드 생성(Artificial Intelligence Code Generation, AI Code Generation)**: 모델이 구현과 테스트 후보를 만드는 개발 지원 기법이다.
- **거대 언어 모델(Large Language Model, LLM)**: 대규모 텍스트와 코드로 학습해 다음 토큰을 생성하는 모델이다.
- **정확성(Correctness)**: 생성 코드가 요구한 동작을 올바르게 수행하는 성질이다.
- **보안(Security)**: 생성 코드에 악용 가능한 취약점이 없는 성질이다.
- **출처(Provenance)**: 생성 코드의 기원과 생성 근거를 추적할 수 있는 정보다.

</details>

- 정의/개념: LLM이 요구사항과 코드 문맥을 바탕으로 구현•테스트 후보를 만들고 개발자가 검증해 반영하는 **AI 코드 생성 기반 소프트웨어 개발 지원 기법**이다.
- 배경/필요성: 확률적 생성만으로는 **정확성•보안•출처 보장할 수 없다**.

#### 한줄 요약

- LLM 초안과 **개발자 독립 검증 기반 코드 반영**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **문맥 생성**: 허용한 코드•주석•지시를 모델 입력으로 구성해 후보를 만드는 활동이다.
- **독립 검증**: 생성과 분리된 기대 결과•시험•검토로 후보의 옳음을 확인하는 활동이다.
- **위험 통제**: 환각•취약점•권리 문제를 검사하고 반영을 제한하는 절차이다.

</details>

- **문맥 생성**: 허용한 코드•주석으로 후보 작성이다.
- **독립 검증**: 기대 결과와 누락 조건을 확인한다.
- **위험 통제**: 환각•취약점•권리 문제 점검이다.

#### 한줄 요약

- 문맥 생성•독립 검증•**보안•권리 위험 통제**가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **컨텍스트 수집 엔진(Context Collection Engine)**: 허용된 코드•파일•지시를 모델 입력으로 구성하는 기능이다.
- **거대 언어 모델(Large Language Model, LLM)**: 대규모 텍스트와 코드로 학습한 생성 모델이다.
- **정책 검사(Policy Check)**: 생성 후보가 사용 정책을 지키는지 확인하는 검사다.
- **참조 검사(Reference Check)**: 생성 후보와 공개 코드의 일치 정보를 확인하는 검사다.
- **코드 수정(Code Revision)**: 개발자가 생성 후보를 이해하고 고치는 활동이다.
- **시험(Testing)**: 생성 코드의 기대 동작을 실행해 확인하는 활동이다.
- **보안 검사(Security Check)**: 생성 코드의 취약점을 확인하는 활동이다.
- **동료 검토(Peer Review)**: 다른 개발자가 생성 코드의 적합성을 확인하는 활동이다.

</details>

```text
[컨텍스트 수집 엔진]
          |
 [LLM 코드 생성 모델]
          |
   [정책•참조 검사]
          |
  [개발자 검증 경로]
```

선의 의미: 컨텍스트 수집 엔진과 LLM 코드 생성 모델의 선은 허용 코드•파일•지시 제공 관계, 생성 모델과 정책•참조 검사의 선은 코드 후보와 생성 근거의 검사 관계, 정책•참조 검사와 개발자 검증 경로의 선은 검사 정보와 후보를 바탕으로 수정•시험•보안•동료 검토를 수행하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 컨텍스트 수집 엔진 | 허용 코드•파일•지시를 **모델 입력으로 구성** |
| LLM 코드 생성 모델 | 지시•문맥에 맞는 **코드 후보** 생성 |
| 정책•참조 검사 | **사용 정책•공개 코드 일치** 정보 제공 |
| 개발자 검증 경로 | **수정•시험•보안•동료 검토** 후 반영 |

#### 한줄 요약

- 문맥•생성•정책•**개발자 검증 구조**가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **프롬프트(Prompt)**: 구현 의도와 제약을 담은 모델 지시다.
- **제한 문맥(Restricted Context)**: 권한 경계 안의 코드만 담은 모델 입력이다.
- **코드 후보(Code Candidate)**: 모델이 만든 구현 초안이다.
- **생성 문맥(Generation Context)**: 코드 후보 생성에 사용한 입력 정보다.
- **빌드 결과(Build Result)**: 생성 코드의 컴파일과 패키징 결과다.
- **단위 테스트 결과(Unit-test Result)**: 작은 코드 단위의 동작 검증 결과다.
- **검토 결과(Review Result)**: 사람이 생성 코드의 적합성을 판정한 결과다.
- **정적 애플리케이션 보안 테스트(Static Application Security Testing, SAST)**: 실행 없이 코드의 취약 패턴을 찾는 검사다.
- **프롬프트•제한 문맥 구성**: 구현 의도와 권한 안의 최소 코드만 모델 입력으로 만드는 동작이다.
- **코드 후보•생성 문맥 생성**: 모델이 초안과 생성에 사용한 입력 근거를 함께 제공하는 동작이다.
- **정책•참조 검사**: 사용 정책과 공개 코드 유사성 및 출처 정보를 확인하는 동작이다.
- **개발자 수정•기대 동작 정의**: 사람이 후보를 이해•수정하고 독립된 성공•실패 조건을 정하는 동작이다.
- **빌드•시험•SAST•동료 검토**: 수정 코드를 자동 검증과 사람 검토에 통과시키는 동작이다.

</details>

```text
[구현 의도•허용 파일 범위]
          |
          v
+----------------------------------+
| 1. 프롬프트•제한 문맥 구성      |
+----------------------------------+
          |
          v
+----------------------------------+
| 2. 코드 후보•생성 문맥 생성     |
+----------------------------------+
          |
          v
+----------------------------------+
| 3. 정책•참조 검사               |---- 위반 ----> [후보 폐기]
+----------------------------------+
          |
          v
+----------------------------------+
| 4. 개발자 수정•기대 동작 정의  |
+----------------------------------+
          |
          v
+----------------------------------+
| 5. 빌드•시험•SAST•동료 검토    |---- 실패 ----> [수정•재검증]
+----------------------------------+
          |
          v
[검증된 코드 반영]
```

**동작 원리**

1. **프롬프트•제한 문맥 구성**: 최소 권한 입력을 제공한다.
2. **코드 후보•생성 문맥 생성**: 초안•입력 근거를 제공한다.
3. **정책•참조 검사**: 정책•공개 코드 유사성을 확인한다.
4. **개발자 수정•기대 동작 정의**: 독립 조건을 명시한다.
5. **빌드•시험•SAST•동료 검토**: 코드를 검증한다.

> 요약: 허용 문맥으로 생성한 초안을 사람•시험•보안•권리 검토를 거쳐 반영한다.

#### 한줄 요약

- 제한 문맥•정책•**개발자 독립 검증 흐름**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **AI 기반 코드 생성**: 넓은 코드 문맥으로 함수•알고리즘•테스트 초안을 만드는 방식이다.
- **통합 개발 환경(Integrated Development Environment, IDE)**: 코드 작성과 빌드 및 디버깅을 통합한 도구다.
- **전통적 자동 완성(Traditional Code Completion)**: 타입과 구문으로 짧은 코드 후보를 제공하는 기능이다.
- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능을 정해진 요청•응답 계약으로 호출하게 하는 인터페이스다.
- **환각(Hallucination)**: 모델이 사실과 다른 코드나 API를 생성하는 현상이다.
- **취약점(Vulnerability)**: 생성 코드에 포함된 악용 가능한 보안 결함이다.
- **공개 코드 유사성(Public-code Similarity)**: 생성 후보가 공개 코드와 비슷한 정도다.

</details>

| 판단 기준 | AI 기반 코드 생성 | 전통적 IDE 자동 완성 |
|:---|:---|:---|
| 적용 기준 | 문맥 기반 **구현 초안** 필요 | 결정적 **구문 후보** 필요 |
| 핵심 특징 | **함수•알고리즘•테스트 후보** 생성 | **멤버•키워드•구문** 완성 |
| 한계 | **환각•취약점•공개 코드 유사성** | 잘못된 **멤버•타입 선택** |

> 요약: 언어 모델은 넓은 문맥만큼 검증 범위가 큼이 핵심이다.

#### 한줄 요약

- 구문 후보는 자동 완성, 구현 초안은 **AI 생성**이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **문맥 제외(Context Exclusion)**: 기밀 코드를 모델 입력에서 빼는 통제다.
- **최소 문맥(Minimum Context)**: 작업에 필요한 코드만 모델에 제공하는 통제다.
- **비밀 탐지(Secret Detection)**: 자격증명의 모델 입력 포함 여부를 찾는 통제다.
- **공식 문서•빌드•시험•SAST**: 존재하지 않는 API와 취약 로직을 확인하는 독립 검증 수단이다.
- **코드 참조 검사(Code Reference Check)**: 공개 코드 유사 제안의 출처를 확인하는 절차다.
- **라이선스 검사(License Check)**: 제안 코드의 사용 조건을 확인하는 절차다.
- **지식재산(Intellectual Property, IP)**: 창작물•발명•표지 등 법으로 보호되는 무형 자산이다.
- **지식재산 검사(IP Check)**: 생성 코드의 권리 침해 위험을 확인하는 절차다.
- **기대 결과•실패 조건 독립 설계**: 생성 코드와 같은 가정을 되풀이하지 않도록 요구를 근거로 정상 결과와 오류 조건을 별도로 정하는 방식이다.
- **총시간(Total Time)**: 생성부터 검증과 반영까지 걸린 시간이다.
- **수정량(Revision Volume)**: 생성 후보를 고친 코드의 양이다.
- **결함 수(Defect Count)**: 생성 코드에서 발견된 결함의 수다.
- **검토 통과율(Review Pass Rate)**: 생성 후보가 검토를 통과한 비율이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기밀 코드•자격증명이 모델 문맥으로 외부 노출 | **제외•최소 문맥•비밀 탐지** 적용 | **외부 정보 노출** 감소 |
| 존재하지 않는 API•취약 로직을 그럴듯하게 생성 | **공식 문서•빌드•시험•SAST** 확인 | **환각•취약 로직** 차단 |
| 공개 코드와 유사한 제안을 그대로 반영해 권리 침해 | **코드 참조•라이선스•IP 검사** | **권리 침해 위험** 감소 |
| 생성 코드와 테스트가 같은 잘못된 가정을 공유 | **기대 결과•실패 조건 독립 설계** | **동일 가정 반복** 방지 |
| 생성 시간만 측정해 수정•검토•결함 비용을 은폐 | **총시간•수정량•결함•검토 통과율** 측정 | **실제 절감 효과** 판단 |

> 적용 사례: 데이터 변환 코드 초안을 생성하고 수정량•검토 시간•리뷰 통과율로 실제 효과 측정

#### 한줄 요약

- 문맥•환각•권리•**총검증 비용 기반 효과 측정**이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **문맥 민감도(Context Sensitivity)**: 모델 입력의 정보 노출 위험 정도다.
- **검증 비용(Validation Cost)**: 생성 후보의 검토와 시험에 드는 부담이다.
- **권리 위험(IP Risk)**: 생성 코드가 지식재산권을 침해할 위험이다.
- **생성 코드 반영**: 개발자가 후보를 이해•수정하고 검증한 뒤 제품 코드에 포함하는 결정이다.

</details>

- 문맥 민감도•검증 비용•권리 위험을 기준으로 **생성 코드 반영 결정**이 핵심이다.

#### 한줄 요약

- 문맥•검증•권리 위험 통과 후 **생성 코드 반영**이 핵심이다.
