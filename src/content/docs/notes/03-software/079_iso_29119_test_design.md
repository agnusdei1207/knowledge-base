## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **위험 기반 테스팅 및 설계 기법(RBT & Test Techniques)**: 시스템 위험도에 따라 테스트 강도를 차등화하고 명세 기반(블랙박스), 구조 기반(화이트박스), 경험 기반 기법으로 케이스를 도출하는 체계.
- **테스트 품질 불일치 및 추적성 단절(Quality Inconsistency & Traceability Break)**: 조직마다 파편화된 테스트 기법과 서식으로 인해 요구사항과 테스트 간 추적이 불가능하고 품질 보증에 실패하는 문제.

</details>

- 정의/개념: 소프트웨어 테스팅의 국제 표준화를 위해 **위험 기반(RBT) 프로세스와 명세·구조·경험 기반 설계 기법(Part 4)**을 체계화한 ISO/IEC/IEEE 국제 표준
- 배경/필요성: 조직별 테스트 용어 및 설계 기법 파편화로 인한 **테스트 품질 불일치, 요구사항 추적성 단절 및 시험 결과 상호 검증 불가 한계** 직면

#### 한줄 요약

- 위험 기반 테스팅 사상과 3대 테스트 설계 기법을 표준화하여 소프트웨어 시험 전 주기의 품질을 보증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **5개 파트 표준 구조(5-Part Structure)**: Part 1(개념/정의), Part 2(테스트 프로세스), Part 3(문서 양식), Part 4(테스트 설계 기법), Part 5(키워드 주도 테스트).
- **테스트 4단계 계층(Basis $\rightarrow$ Condition $\rightarrow$ Case $\rightarrow$ Procedure)**: 요구사항 분석에서 실행 스크립트 작성까지 이어지는 정형화된 테스트 설계 절차.

</details>

- 파편화된 기존 테스트 표준(IEEE 829, BS 7925 등)을 통합한 **국제 단일 표준 체계**
- 위험도에 따라 테스트 우선순위를 결정하는 **위험 기반 테스팅(RBT) 사상 반영**
- 요구사항(SRS)부터 테스트 케이스 및 실행 결과까지의 **완전한 양방향 추적성(Traceability) 보장**

#### 한줄 요약

- RBT 위험 분석과 4단계 정형 설계 절차를 통해 테스트의 커버리지와 신뢰성을 극대화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Part 4 3대 설계 기법 분류**: 명세 기반(동등분할, 경계값), 구조 기반(구문, 분기, MC/DC), 경험 기반(오류추정, 탐색적 테스팅).

</details>

```text
[ ISO/IEC/IEEE 29119-4 테스트 설계 기법 아키텍처 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                   ISO/IEC/IEEE 29119-4 Test Techniques                 │
 ├────────────────────────┬────────────────────────┬──────────────────────┤
 │ 1. 명세 기반 (블랙박스) │ 2. 구조 기반 (화이트박스)│ 3. 경험 기반         │
 ├────────────────────────┼────────────────────────┼──────────────────────┤
 │ • 동등 분할 (EP)       │ • 구문 커버리지 ($C_0$)│ • 오류 추정          │
 │ • 경계값 분석 (BVA)    │ • 분기 커버리지 ($C_1$)│ • 탐색적 테스팅      │
 │ • 의사결정 테이블      │ • 조건 커버리지 ($C_2$)│ • 체크리스트 기반    │
 │ • 상태 전이 테스팅     │ • MC/DC Coverage       │                      │
 └────────────────────────┴────────────────────────┴──────────────────────┘
```

선의 의미: 소프트웨어 테스트 대상을 다각도로 검증하기 위해 정형화된 3대 설계 기법 분류 체계.

| 구성요소 | 책임 |
|:---|:---|
| 명세 기반 기법 (Specification) | 요구사항 명세서 기반으로 **동등분할, 경계값분석, 의사결정테이블 설계** |
| 구조 기반 기법 (Structure) | 소스코드 제어/데이터 흐름 기반으로 **구문, 분기, MC/DC 커버리지 설계** |
| 경험 기반 기법 (Experience) | 테스터의 도메인 직관을 활용하여 **오류 추정 및 탐색적 테스팅 보완** |
| 양방향 추적 매트릭스 (TTM) | 요구사항 ID와 **테스트 조건, 케이스, 실행 절차 간 1:1 매핑 관리** |

#### 한줄 요약

- 명세, 구조, 경험 기반의 기법으로 테스트 케이스를 설계하고 추적 매트릭스로 완결성을 검증

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **테스트 베이시스(Test Basis)**: 테스트 조건과 케이스 도출의 근거가 되는 요구사항 정의서, 아키텍처 설계서, 위험 분석서 등 일체의 산출물.

</details>

```text
[ ISO 29119 테스트 설계 4단계 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 테스트 베이시스 분석: 요구명세 수거 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 테스트 조건 도출: 시험 항목 식별    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 테스트 케이스 설계: 입력/기대값 정의│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 테스트 절차 생성: 실행 스크립트 작성│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 테스트 베이시스 분석: 요구사항 정의서, 유스케이스, 위험 분석서를 검토하여 테스트 근거를 수집.
2. 테스트 조건 도출: 무엇을 검증해야 하는지 기능적/비기능적 테스트 조건(Test Condition)을 식별.
3. 테스트 케이스 설계: Part 4의 설계 기법(경계값, 결정테이블 등)을 적용하여 구체적 입력값과 기대결과를 정의.
4. 테스트 절차 생성: 테스트 케이스의 실행 순서, 사전 조건, 환경 설정을 결합한 테스트 프로시저(스크립트)를 작성.

#### 한줄 요약

- 베이시스 분석 $\to$ 조건 도출 $\to$ 케이스 설계 $\to$ 절차 생성의 4단계로 테스트를 구체화

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **IEEE 829 vs ISO 29119**: 문서 서식 위주의 IEEE 829 표준에서 프로세스, 서식, 설계 기법, 위험 기반 사상을 모두 포괄한 ISO 29119로의 진화.

</details>

| 구분 | 기존 IEEE 829 표준 | ISO/IEC/IEEE 29119 통합 표준 |
|:---|:---|:---|
| **적용 기준** | 단순 테스트 문서 양식(Documentation) 준수 | 소프트웨어 테스트 전 수명주기 공학적 표준화 |
| **핵심 특징** | **산출물 서식(Test Plan, Report) 중심 정의** | **위험 기반 테스팅(RBT) 및 Part 4 정형 설계 기법 통합** |
| **한계** | 설계 기법 및 커버리지 측정 가이드라인 부재 | 전체 파트 적용 시 소규모 프로젝트 문서화 오버헤드 |

#### 한줄 요약

- IEEE 829는 서식에 치중했으나 ISO 29119는 프로세스, 서식, 설계 기법을 종합 통합

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **테스트 프로세스 테일러링(Test Tailoring)**: 프로젝트 규모, 위험도, 개발 모델(Agile/Waterfall)에 따라 ISO 29119 산출물과 프로세스를 유연하게 재단하는 활동.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지나치게 방대한 표준 문서 작성으로 인한 프로젝트 지연 | **프로젝트 위험도에 따른 표준 프로세스 및 산출물 테일러링(Tailoring)** | 소요 비용 절감 및 개발 기민성 확보 |
| 요구사항 변경 시 테스트 케이스 불일치 및 추적 단절 | **Test Traceability Matrix(TTM)와 ALM 도구(Jira/Xray) 자동 연동** | 요구사항-테스트 간 양방향 추적성 보장 |
| 테스터 주관에 따른 테스트 커버리지 왜곡 | **Part 4에 규정된 정량적 커버리지 산식(문장, 분기, MC/DC) 공식 적용** | 객관적 테스트 완료 기준(Exit Criteria) 수립 |

#### 한줄 요약

- 프로세스 테일러링, TTM 자동화, 정량 커버리지 적용으로 표준 테스트의 실효성을 극대화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지속적 테스팅(Continuous Testing)**: CI/CD 파이프라인 내에서 ISO 29119 기반 테스트 케이스를 자동 실행하여 결함을 조기 발견하는 자동화 체계.

</details>

- **ISO/IEC/IEEE 29119**는 글로벌 수준의 소프트웨어 품질을 보증하는 핵심 가이드라인이며, 위험 기반 테스트 설계와 CI/CD 자동화 도구를 융합하여 무결점 소프트웨어를 납품해야 함

#### 한줄 요약

- 국제 표준 설계 기법과 위험 기반 테스팅을 통해 소프트웨어 테스트의 정밀도와 신뢰성을 보증
