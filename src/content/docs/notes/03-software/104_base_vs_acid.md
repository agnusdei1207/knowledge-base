## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ACID vs BASE**: 즉각적인 무결성과 엄격한 직렬화를 보장하는 ACID(관계형 모델)와 기본 가용성(BA), 유연한 상태(Soft-state), 최종 일관성(Eventual Consistency)을 지향하는 BASE(분산 모델).
- **글로벌 2PC 잠금 병목 및 시스템 결합(2PC Lock & Coupling)**: 분산 환경에서 단일 ACID 트랜잭션을 강제할 때 발생하는 분산 락 지연과 전면 장애 전파 위험.

</details>

- 정의/개념: 데이터베이스 트랜잭션 모델에서 **강한 일관성 중심의 ACID와 분산 고가용성·최종일관성 중심의 BASE** 활용 비교한 데이터 정합성 설계 패러다임
- 배경/필요성: 마이크로서비스(MSA) 및 대규모 분산 환경에서 단일 ACID 트랜잭션 강행 시 발생하는 **글로벌 2PC 잠금 병목 및 시스템 전면 장애 전파 위험** 직면

#### 한줄 요약

- 핵심 원장은 ACID로 엄격히 관리하고 대규모 분산 파생 상태는 BASE 모델로 최종 일관성을 달성

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최종 일관성(Eventual Consistency)**: 데이터 갱신 후 복제 지연(Replication Lag)이 존재할 수 있으나 일정 시간이 경과하면 모든 분산 노드가 동일한 최신 데이터로 수렴하는 속성.
- **보상 트랜잭션(Compensating Transaction)**: BASE 기반 Saga 패턴에서 후속 비즈니스 실패 시 이미 커밋된 이전 단계의 작업을 취소하기 위해 반대(Reverse) 연산을 실행하는 기법.

</details>

- 금융/결제 등 엄격한 정합성을 위한 **즉각적 강한 일관성(Strict ACID)**
- 대규모 트래픽과 서비스 독립성을 위한 **최종 일관성 및 고가용성(BASE)**
- 트랜잭셔널 아웃박스(Transactional Outbox) 및 Saga 패턴을 통한 **비동기 이벤트 수렴** #### 한줄 요약

- ACID의 무결성과 BASE의 가용성을 분리 적용하여 대규모 분산 시스템의 신뢰성과 성능을 양립

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Transactional Outbox Pattern**: 비즈니스 데이터 갱신과 이벤트 발행을 로컬 ACID 트랜잭션으로 원자 커밋한 후 CDC(Debezium)를 통해 분산 노드로 전파하는 패턴.

</details>

```text
[ ACID 및 BASE 하이브리드 트랜잭션 아키텍처 ]

 1. [ 주문 서비스 (ACID 로컬 트랜잭션) ]
    Order Table Insert + Outbox Table Insert ──► (단일 DB Local Commit!)
                                                        │ (CDC 이벤트 발행)
                                                        ▼
 2. [ 이벤트 브로커 (Kafka / Message Queue) ] ──────────┼──────────────────┐
                                                        │                  │
                                                        ▼                  ▼
 3. [ 결제 서비스 (BASE 최종 일관성) ]        [ 배송 서비스 ]    [ 알림 서비스 ]
    - 멱등 컨슈머 (Idempotent Consumer)        - 최종 수렴       - 최종 수렴
    - 실패 시 보상 트랜잭션 (Saga Rollback)
```

선의 의미: 주문 서비스는 단일 DB 내에서 ACID로 확정하고, 후속 서비스들은 비동기 이벤트를 통해 BASE 최종 일관성으로 수렴하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| ACID 모델 | 단일 서비스 내부에서 **원자성, 일관성, 격리성, 지속성을 100% 즉각 보장** |
| Basically Available (BA) | 일부 분산 노드 장애 시에도 **전체 시스템이 중단되지 않고 가용 응답 유지** |
| Soft-State (S) | 비동기 복제 지연 시간 동안 **데이터 상태가 점진적으로 변화함을 허용** |
| Eventual Consistency (E) | 추가 변경이 없을 때 **시간 경과에 따라 모든 분산 복제본이 동일한 값으로 수렴** |

#### 한줄 요약

- 로컬 서비스는 ACID로 무결성을 확정하고 분산 서비스 간 연계는 BASE로 가용성과 최종 수렴을 달성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **아웃박스 기반 비동기 수렴 파이프라인**: 로컬 원자 커밋 $\to$ CDC 이벤트 발행 $\to$ 멱등 컨슈머 처리 $\to$ 파생 상태 갱신 $\to$ 최종 일관성 확인.

</details>

```text
[ Transactional Outbox 기반 BASE 수렴 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 로컬 원자 커밋: 데이터 + Outbox 저장│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. CDC 이벤트 발행: Kafka 브로커 전달  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 멱등 이벤트 처리: 중복 수신 방지    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 파생 상태 갱신: 후속 MSA 로컬 반영  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 수렴 상태 확인: 최종 일관성 달성    │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 로컬 원자 커밋: 주문 서비스가 비즈니스 데이터와 이벤트 메시지를 단일 DB의 Outbox 테이블에 함께 ACID로 커밋.
2. CDC 이벤트 발행: Debezium이나 폴러가 Outbox 테이블을 감지하여 메시지 브로커(Kafka)로 신뢰성 있게 발행.
3. 멱등 이벤트 처리: 결제 및 재고 서비스가 메시지를 수신하고 멱등 키(Idempotency Key)를 검사하여 중복 실행을 차단.
4. 파생 상태 갱신: 각 마이크로서비스가 자신의 로컬 데이터베이스에 상태를 반영.
5. 최종 일관성 달성: 일시적 복제 지연 후 모든 분산 서비스의 데이터가 일치 상태로 완벽히 수렴.

#### 한줄 요약

- 로컬 커밋 $\to$ 이벤트 발행 $\to$ 멱등 처리 $\to$ 파생 갱신 $\to$ 최종 일관성 수렴의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ACID vs BASE 패러다임 비교**: 강한 일관성의 전통적 RDBMS 모델(ACID)과 고가용성 중심의 현대 분산 MSA 모델(BASE).

</details>

| 구분 | ACID (전통적 관계형 모델) | BASE (현대적 분산 NoSQL/MSA 모델) |
|:---|:---|:---|
| **적용 기준** | 계좌 이체, 결제, 재고 차감 등 엄격한 정합성 도메인 | SNS 피드, 장바구니, 알림, 대규모 로그 수집 |
| **핵심 특징** | **즉시 강한 일관성(Strict), 2PL/WAL 기반 원자적 수행** | **기본 가용성(BA), 유연한 상태(Soft-state), 최종 일관성** |
| **한계** | 분산 노드 확장 시 잠금 대기 및 성능 저하 (Scale 한계) | 즉각적 데이터 불일치(Stale Data) 및 보상 트랜잭션 필요 |

#### 한줄 요약

- 정밀 금융 도메인은 ACID, 대규모 분산 확장 도메인은 BASE 모델을 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **멱등성 보장(Idempotency Guarantee)**: 동일한 메시지가 네트워크 재시도로 2번 이상 전달되더라도 시스템 상태가 한 번만 반영되도록 하는 방어 설계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비동기 메시지 전파 중 브로커 다운으로 메시지 유실 | **Transactional Outbox Pattern 및 Debezium CDC 적용** | 이벤트 발행의 원자성 및 전달 보장 |
| 네트워크 재시도로 인한 중복 메시지 수신 (At-Least-Once) | **Idempotency Key 검증 및 Unique 제약조건 기반 멱등 컨슈머 구현** | 중복 결제 및 중복 차감 원천 방지 |
| 분산 연쇄 처리 중 특정 서비스 실패로 인한 정합성 파괴 | **Saga Pattern(코레오그래피/오케스트레이션) 보상 트랜잭션 자동화** | 실패 시 이전 완료 단계 자동 원복 |

#### 한줄 요약

- 아웃박스 패턴, 멱등 컨슈머, Saga 보상 트랜잭션을 결합하여 BASE 분산 정합성을 완성

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **도메인 격리 트랜잭션 설계(Domain-Isolated Transaction Design)**: 시스템의 도메인 특성에 따라 핵심 원장은 ACID로 묶고 연계 기능은 BASE로 분리하는 현대적 설계 기법.

</details>

- **ACID와 BASE** 기반 상호 대립되는 개념이 아닌 현대 엔터프라이즈 아키텍처의 상호 보완재이며, 핵심 원장은 ACID로 철저히 보호하고 분산 서비스 간 연계는 BASE 최종 일관성으로 설계하여 최고 수준의 가용성과 안정성을 달성해야 함

#### 한줄 요약

- 로컬 트랜잭션의 ACID와 분산 연계의 BASE를 결합하여 고성능·고가용성 엔터프라이즈 시스템을 완성
