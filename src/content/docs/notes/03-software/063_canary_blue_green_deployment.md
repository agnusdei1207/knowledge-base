## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **배포 전략**: 새 버전의 트래픽 노출과 환경 전환을 제어해 운영 위험을 제한하는 방식이다.
- **카나리 배포(Canary Deployment)**: 새 버전을 일부 트래픽부터 점진 확대하는 전략이다.
- **블루-그린 배포(Blue-Green Deployment)**: 구버전과 신버전 환경의 전체 라우팅을 전환하는 전략이다.
- **전체 사용자 영향(Full-user Impact)**: 배포 실패가 모든 사용자 요청에 확산되는 위험이다.
- **복구 지연(Recovery Delay)**: 실패한 배포의 정상화가 늦어지는 위험이다.

</details>

- 정의/개념: **카나리 배포**는 트래픽을 점진 확대하고, **블루-그린 배포**는 병렬 환경의 전체 라우팅을 전환하는 **배포 전략**이다.
- 배경/필요성: 일괄 교체 시 **전체 사용자 영향**과 **복구 지연**이 발생할 수 있다.

#### 한줄 요약

- **카나리 배포**의 점진 노출과 **블루-그린 배포**의 병렬 환경 전환이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **점진 노출(Progressive Exposure)**: 후보 버전의 트래픽을 조금씩 늘리는 원칙이다.
- **영향 범위 제한(Blast-radius Limitation)**: 후보 결함이 미치는 요청 범위를 줄이는 원칙이다.
- **병렬 환경(Parallel Environment)**: 구버전과 신버전 환경을 동시에 준비하는 구조이다.
- **즉시 전환(Instant Switch)**: 라우팅만 바꾸어 버전을 빠르게 전환하는 방식이다.
- **데이터 호환(Data Compatibility)**: 두 버전이 같은 데이터를 안전하게 사용하는 성질이다.
- **인터페이스 호환(Interface Compatibility)**: 두 버전이 같은 계약을 안전하게 사용하는 성질이다.

</details>

- 카나리는 **점진 노출**과 **영향 범위 제한**을 적용한다.
- 블루-그린은 **병렬 환경**과 **즉시 전환**을 적용한다.
- 구•신 버전은 **데이터 호환**과 **인터페이스 호환**을 유지한다.

#### 한줄 요약

- **점진 노출**과 **즉시 전환**의 위험 통제 방식 차이가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **배포 제어기(Deployment Controller)**: 관찰 기준에 따라 노출 확대•전환•복귀 정책을 실행하는 구성요소이다.
- **트래픽 라우터(Traffic Router)**: 요청을 안정•후보 버전에 비율 배분하거나 전체 전환하는 구성요소이다.
- **관측 시스템(Observability System)**: 버전별 오류•지연•업무 성공률을 수집하고 판정하는 구성요소이다.

</details>

```text
[배포 제어기] -------- [트래픽 라우터]
       |                    /       \
       |                   /         \
       |            [안정 환경]     [후보 환경]
       |                 \           /
       |                  \         /
       +--------------- [관측 시스템]
```

선의 의미: 배포 제어기와 트래픽 라우터의 선은 트래픽 가중치•대상 정책 관계, 라우터와 두 환경의 선은 요청 배분 관계, 두 환경과 관측 시스템의 선은 버전별 운영 지표 수집 관계, 관측 시스템과 배포 제어기의 선은 확대•전환•복귀 판단 자료 제공 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 배포 제어기 | 확대•전환•복귀 정책 실행 |
| 트래픽 라우터 | 버전별 트래픽 가중치와 대상 제어 |
| 안정 환경 | 검증된 안정 버전 서비스 제공 |
| 후보 환경 | 새 버전의 제한•대체 서비스 제공 |
| 관측 시스템 | 버전별 운영 지표 수집•판정 |

#### 한줄 요약

- **배포 제어기**, **트래픽 라우터**, **관측 시스템**의 폐루프 제어 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **버전 산출물(Version Artifact)**: 후보 환경에 배포하는 실행 이미지•패키지와 설정 묶음이다.
- **호환성 규칙(Compatibility Rule)**: 구•신 버전이 공유 데이터와 인터페이스를 함께 사용하도록 정한 규칙이다.
- **트래픽 가중치(Traffic Weight)**: 전체 요청 중 특정 버전으로 보낼 비율을 지정하는 라우팅 값이다.
- **관찰 기준(Observation Criteria)**: 오류율•지연•업무 성공률로 확대•중단•복귀를 판단하는 조건이다.
- **카나리 확대•복귀**: 버전별 지표가 기준을 통과하면 후보 노출을 늘리고 위반하면 안정 버전으로 되돌리는 흐름이다.
- **블루-그린 전환•복귀**: 후보 환경을 검증한 뒤 전체 라우팅을 바꾸고 이상 시 즉시 원래 환경으로 돌리는 흐름이다.

</details>

```text
[공통 준비: 버전 산출물•호환성 검증]
                    |
                    v
+-- 카나리 확대•복귀 --------+
| 후보 제한 노출             |
|          |                 |
|          v                 |
| 버전별 지표 판정           |
|     +----+----+            |
|     | 통과  | 위반         |
|     v       v              |
| 노출 확대  안정 버전 복귀  |
|     |                      |
|     `-- 다음 단계 반복     |
+----------------------------+

              또는

+-- 블루-그린 전환•복귀 -----+
| 후보 환경 전체 검증        |
|          |                 |
|          v                 |
| 전체 라우팅 전환           |
|          |                 |
|          v                 |
| 전환 후 지표 판정          |
|     +----+----+            |
|     | 정상  | 이상         |
|     v       v              |
| 신환경 유지  구환경 복귀    |
+----------------------------+
```

### 동작 원리

1. **버전 산출물**과 **호환성 규칙**을 공통 준비 단계에서 검증한다.
2. 카나리는 **트래픽 가중치**로 후보를 제한 노출하고 **관찰 기준**에 따라 **카나리 확대•복귀**를 반복한다.
3. 블루-그린은 후보 환경을 전체 검증한 뒤 **블루-그린 전환•복귀**로 라우팅을 바꾸거나 되돌린다.

> 요약: 호환성을 확보한 뒤 운영 지표로 후보 버전의 확대 또는 복귀를 결정한다.

#### 한줄 요약

- **카나리 확대•복귀**와 **블루-그린 전환•복귀**의 제어 흐름이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **점진 위험 검증**: 소수 트래픽부터 운영 지표를 관찰해 후보 버전의 위험을 단계적으로 확인하는 방식이다.
- **환경 전환 복구**: 병렬 환경의 라우팅 대상을 바꾸어 전체 버전을 전환하거나 이전 환경으로 되돌리는 방식이다.

</details>

| 배포 전략 | 카나리 배포 | 블루-그린 배포 |
|:---|:---|:---|
| 적용 기준 | **점진 위험 검증**과 영향 범위 최소화 | 빠른 전환과 **환경 전환 복구** |
| 핵심 특징 | 후보 트래픽의 단계적 확대 | 병렬 환경의 일괄 전환 |
| 한계 | 장시간 공존과 지표 판정 복잡성 | 이중 자원과 전환 시 전체 영향 |

> 요약: 점진 관찰은 카나리, 병렬 환경 전환은 블루-그린이 핵심이다.

#### 한줄 요약

- **점진 위험 검증**에는 **카나리 배포**, **환경 전환 복구**에는 **블루-그린 배포**가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **확장-축소 변경(Expand-Contract Change)**: 구•신 버전이 함께 사용할 구조를 먼저 추가하고 전환 후 이전 구조를 제거하는 방식이다.
- **멱등성(Idempotency)**: 같은 요청을 반복 처리해도 결과가 한 번 처리한 것과 같은 성질이다.
- **보상 절차(Compensation Procedure)**: 이미 발생한 외부 부작용을 반대 업무로 상쇄하는 절차이다.
- **버전별 지표(Per-version Metric)**: 후보와 안정 버전별로 집계한 운영 측정값이다.
- **사용자군별 지표(Per-cohort Metric)**: 코호트별로 집계한 운영 측정값이다.
- **코호트(Cohort)**: 지역•계정•기기처럼 같은 특성을 기준으로 묶어 후보 버전에 노출하는 사용자 집단이다.
- **최소 표본(Minimum Sample)**: 희귀 오류까지 판단하는 데 필요한 요청 수이다.
- **관찰 시간(Observation Window)**: 후보 지표를 평가할 최소 기간이다.
- **업무별 트래픽(Business Traffic Mix)**: 핵심 업무 시나리오별 요청 구성이다.
- **노출 제한(Exposure Limit)**: 후보 버전이나 외부 부작용에 영향을 받을 수 있는 사용자•요청 비율의 상한이다.
- **용량 계획(Capacity Planning)**: 병렬 환경에 필요한 자원을 미리 산정하는 활동이다.
- **유휴 환경 자동 회수(Idle Environment Reclamation)**: 전환 뒤 쓰지 않는 환경 자원을 자동 해제하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비가역 데이터 변경으로 이전 버전 복귀 실패 | **확장-축소 변경**으로 동시 호환 | 복귀 시 데이터 오류 방지 |
| 표본•관찰 시간이 작아 드문 결함 미탐지 | **최소 표본**, **관찰 시간**, **업무별 트래픽** 구성 | 희귀 결함 판정 근거 확보 |
| 버전•사용자군 지표 혼합으로 후보 이상 은폐 | **버전별 지표**와 **코호트**별 **사용자군별 지표** 분리 | 후보 버전 이상 조기 탐지 |
| 복귀 후에도 결제•알림 부작용이 잔존 | **멱등성**, **보상 절차**, **노출 제한** 적용 | 중복 결제•알림 피해 감소 |
| 블루-그린 유휴 환경 유지로 자원 비용 증가 | **용량 계획**과 **유휴 환경 자동 회수** | 병렬 운영 비용 통제 |

> 적용 사례: 결제 서비스는 1% 카나리 트래픽의 오류율을 관찰한 뒤 노출을 확대

#### 한줄 요약

- **확장-축소 변경**, **최소 표본**, **버전별 지표**, **보상 절차**가 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **배포 전략 선택 기준**: 점진 관찰 필요성, 전환 속도, 병렬 자원 비용, 데이터 호환성을 함께 평가해 카나리와 블루-그린 중 하나를 정하는 기준이다.

</details>

- **배포 전략 선택 기준**에 따라 **점진 위험 검증**에는 **카나리 배포**, 즉시 **환경 전환 복구**에는 **블루-그린 배포**를 선택한다.

#### 한줄 요약

- 관찰 방식과 복구 방식에 맞는 **배포 전략 선택 기준**이 핵심이다.
