## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **카나리 배포(Canary Deployment)**: 광산의 카나리아 새처럼, 신규 버전을 전체의 1~5% 소수 트래픽에만 먼저 노출하여 실환경 반응을 검증한 후 점진 확대하는 배포 기법.
- **블루-그린 배포(Blue-Green Deployment)**: 기존 운영 환경(Blue)과 동일한 신규 환경(Green)을 병렬 구축해두고 로드밸런서 라우팅을 한 번에 스위칭하는 무중단 배포 기법.

</details>

- 정의/개념: 무중단 릴리즈를 위해 **트래픽을 점진 노출(Canary)하거나 이중 환경을 스위칭(Blue-Green)** 하는 제로 다운타임 배포 전략
- 배경/필요성: 인플레이스(In-place) 덮어쓰기 배포 시 발생하는 **서비스 중단 시간(Downtime) 및 장애 발생 시 즉각 롤백 불가 해결 불가**

#### 한줄 요약
- 카나리는 점진 노출로 장애 범위를 최소화하고, 블루-그린은 이중 환경 전환으로 즉각 롤백을 지원한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Blast Radius(장애 파급 반경)**: 배포 실패 시 장애의 영향을 받게 되는 사용자 또는 시스템의 물리적/논리적 범위.
- **Router Switching**: DNS 또는 L7 인그레스(Ingress) 라우팅 테이블 변경을 통해 트래픽 대상을 1초 미만으로 전환하는 기법.

</details>

- 카나리: **장애 파급 반경(Blast Radius)을 초기 1~5%로 제한**하여 위험 극소화
- 블루-그린: 구버전(Blue)과 신버전(Green) 병렬 운용 후 **라우터 스위칭을 통한 즉시 전환**
- 결함 감지 시 라우팅 룰 원복만으로 수 초 내 **즉각 롤백(Fast Rollback)** 보장

#### 한줄 요약
- 카나리는 점진 노출로 위험을 최소화하고, 블루-그린은 병렬 환경으로 즉각 전환/롤백을 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Argo Rollouts**: Kubernetes 환경에서 NGINX/Envoy와 연계하여 가중치 기반 트래픽 분할(Canary)과 메트릭 분석을 수행하는 컨트롤러.

</details>

```text
[카나리 및 블루-그린 배포 구조]
|-- L7 트래픽 라우터 (Ingress Controller / Service Mesh)
|   |-- [카나리 모드: 가중치 분할]
|   |   |-- 95% -> Blue Pods (기존 안정 버전: v1.0)
|   |   `-- 5%  -> Canary Pods (신규 점진 버전: v2.0)
|   `-- [블루-그린 모드: 100% 스위칭]
|       |-- [전환 전] 100% -> Blue 환경 (v1.0 활성화)
|       `-- [전환 후] 100% -> Green 환경 (v2.0 활성화, Blue는 대기/종료)
`-- 공통 인프라 계층 (Redis 세션 외장화 & Expand-Contract DB 스키마)
```

선의 의미: 계층 및 라우터 기반 트래픽 분할/스위칭 구조

| 배포 컴포넌트 | 카나리 배포 (Canary) | 블루-그린 배포 (Blue-Green) |
|:---|:---|:---|
| **트래픽 제어기** | **가중치 기반 L7 트래픽 분할 (5% $\to$ 20% $\to$ 100%)** | **라우터 엔드포인트 100% 일괄 스위칭** |
| **인프라 리소스 소모** | 신규 Pod 소량만 추가 (비용 효율적) | **기존 인프라의 2배 규모 필요 (비용 높음)** |
| **버전 공존 여부** | **배포 기간 동안 신/구버전 동시 운영 필수** | 스위칭 시점에 단일 버전만 서비스 |
| **롤백 메커니즘** | 카나리 가중치를 0%로 즉시 회수 | 라우터 대상을 다시 Blue로 스위칭 |

#### 한줄 요약
- 라우터가 트래픽을 가중치 분할하거나 일괄 스위칭하며, 관측 시스템이 가드레일을 감시한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ACA(Automated Canary Analysis)**: 프로메테우스 메트릭을 분석하여 카나리 Pod의 에러율이 기준치 이하일 때만 다음 가중치로 자동 승격시키는 엔진.

</details>

```text
[카나리 배포 워크플로우]
신버전(v2.0) 컨테이너 기동 -> 트래픽 5% 할당
        │
   Prometheus가 10분간 에러율 및 지연시간 자동 분석 (ACA)
        │
   에러율이 SLO 가드레일(0.1% 이하)을 만족하는가?
   ┌────┴─────┐
  예           아니오 (에러율 급증)
   │             │
가중치 20% -> 100% 확대 [즉각 롤백] 5% 트래픽 즉시 차단 및 v1.0 유지
배포 완료 후 구버전 종료

[블루-그린 배포 워크플로우]
Blue(v1.0 운영 중) 상태에서 독립된 Green(v2.0) 인프라 구축 -> 내부 스모크 테스트 수행
        │
   L7 라우터 스위칭: 트래픽 100%를 Green으로 즉시 전환
        │
   운영 모니터링: 이상 감지 시 1초 내 Blue로 스위칭 복원, 정상 시 Blue 자원 회수
```

#### 한줄 요약
- 카나리는 가중치 확대 및 ACA 검증으로, 블루-그린은 병렬 인프라 사전 검증 후 스위칭으로 완결된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Rolling vs Blue-Green vs Canary**: 순차 교체(Rolling), 이중 환경 일괄 스위칭(Blue-Green), 점진 가중치 노출(Canary) 3대 무중단 배포 비교.

</details>

| 비교 항목 | 롤링 배포 (Rolling Update) | 블루-그린 배포 (Blue-Green) | 카나리 배포 (Canary) |
|:---|:---|:---|:---|
| 구현 난이도 | **가장 단순 (K8s 기본 지원)** | 중간 (이중 인프라 필요) | 높음 (L7 트래픽 제어 및 ACA 필요) |
| 추가 인프라 비용 | 없음 (최소 오버헤드) | **2배 인프라 비용 발생** | 소폭 추가 (카나리 인스턴스) |
| 장애 파급 반경 | 전체 사용자에 점진 노출 | 전체 사용자에 일괄 노출 | **1~5% 소수 사용자에게만 국소화** |
| 롤백 소요 시간 | 역순 롤링 (수 분 소요) | **스위칭 1초 미만 즉각 복원** | **가중치 회수 1초 미만 즉각 복원** |

#### 한줄 요약
- 비용 최소화는 롤링, 빠른 스위칭은 블루-그린, 리스크 극소화는 카나리를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Expand-Contract 패턴**: 배포 중 신/구버전이 DB를 동시 조회할 때 발생하는 스키마 불일치를 해결하기 위해 컬럼 추가 $\to$ 배포 $\to$ 구컬럼 삭제로 진행하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 배포 중 신/구버전 동시 접속 시 DB 스키마 불일치 충돌 | **Expand-Contract 패턴 기반 2단계 DB 마이그레이션** | 신/구버전 동시 완벽 호환 보장 |
| 블루-그린 배포 시 2배 인프라 비용 발생 | 전환 완료 즉시 **구버전(Blue) 인스턴스 자동 정지(Scale-in)** | 클라우드 인프라 비용 낭비 차단 |
| 카나리 배포 중 인스턴스 간 세션 불일치로 로그아웃 | 세션을 **Redis 클러스터로 외장화(Stateless 아키텍처)** | 배포 중 사용자 세션 및 장바구니 100% 유지 |
| 카나리 분석 지표의 모호성 | **Prometheus + Argo Rollouts AnalysisTemplate** 지표 정량화 | 무인 자동 승격 및 자동 롤백 실현 |

#### 한줄 요약
- Expand-Contract DB 설계, Blue 환경 즉시 축소, Redis 세션 외장화, ACA 자동화로 안정성을 높인다.

## Ⅶ. 결론

- 사용자 트래픽 충격을 최소화해야 하는 핵심 서비스는 **Argo Rollouts 기반 카나리 점진 배포**를 표준 적용하고, 인프라 격리와 초고속 롤백이 요구되는 시스템은 **블루-그린 배포**를 채택

#### 한줄 요약
- 카나리와 블루-그린 배포는 다운타임을 0으로 만들고 롤백 실패 위험을 사전에 차단하는 클라우드 네이티브 무중단 배포의 핵심 축이다.
