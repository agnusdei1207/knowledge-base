## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **무장애 배포(Zero-Downtime Deployment)**: 점검 시간 띄우고 유저들 쫓아내는 일 없이, 서버가 24시간 도는 와중에 몰래 새 버전으로 쓱싹 갈아치우는 궁극의 배포 기술이다.
- **카나리 배포(Canary Deployment)**: 옛 광부들이 탄광에 새(카나리아)를 보내 가스를 확인했듯, 새 버전을 유저 5%에게만 몰래 먹여보고 에러 안 터지면 100%로 늘리는 '간 보기' 배포이다.
- **블루-그린 배포(Blue-Green Deployment)**: 돌아가는 구버전(Blue) 옆에 똑같은 크기의 신버전(Green)을 띄워놓고, 스위치 딱 올려서 1초 만에 트래픽을 확 넘겨버리는 배포이다.

</details>

- 정의: 클라우드 환경에서 서비스 중단 없이 새 버전으로 갈아타기 위한 2대 무장애 배포 전략인 **Canary & Blue-Green Deployment**
- 배경: 덮어쓰기 배포를 했다가 버그 터지면 **복구할 때까지 전면 장애**가 나는 대참사를 막기 위함

#### 한줄 요약

- 점검 공지 안 띄우고, 찔끔 간 보거나(카나리) 옆에 띄우고 확 넘겨버려서(블루-그린) 배포하는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **장애 타격 범위(Blast Radius)**: 배포하다 터졌을 때 유저들이 얼마나 피해를 보냐의 범위로, 카나리는 타격 범위를 5%로 막을 수 있지만 블루-그린은 100%가 타격받는 리스크가 있다.
- **라우팅 스위치(Routing Switch)**: 유저가 앱에 들어오면 로드밸런서(문지기)가 "너는 구버전으로 가, 너는 신버전으로 가" 하고 방향을 꺾어주는 마법의 문이다.

</details>

- 에러 났을 때의 **장애 타격 범위(Blast Radius)**를 5%로 틀어막는 안전빵 **Canary 배포**.
- 구버전/신버전 병렬로 띄워놓고 1초 만에 일괄 전환하는 **Blue-Green 배포**.
- 배포 망해도 L4/L7 라우터 스위치만 내리면 **1초 만에 구버전으로 즉시 롤백** 가능.

#### 한줄 요약

- 카나리는 리스크를 5%로 줄이고, 블루-그린은 스위치 하나로 100% 올인하는 차이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인그레스 컨트롤러 / 서비스 매시(Ingress / Service Mesh)**: 카나리 배포할 때 트래픽을 "구버전 95% : 신버전 5%" 비율로 기가 막히게 쪼개서 뿌려주는 스마트한 분사기이다.

</details>

```text
[ 무장애 배포 십자포화 아키텍처 ]

[ 유저 트래픽 100% ]
         │
         ▼
[ L7 라우터 (Ingress) ] ── (에러/지연시간 감시) ──▶ [ 프로메테우스 (CCTV) ]
  │             │
 (95%)         (5%)
  ▼             ▼
[ Blue (V1) ]  [ Green (V2) ]
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **배포 제어기 (ArgoCD)** | 새 버전(Green) 띄우고, 안 터지면 비율 올리고 터지면 롤백하는 지휘관 |
| **트래픽 라우터 (Ingress)** | 유저 트래픽을 Blue와 Green으로 95:5 비율로 갈라치는 문지기 |
| **Blue (구버전)** | 현재 평화롭게 돈 벌어오고 있는 검증된 기존 서버 |
| **Green / Canary (신버전)** | 새로 짠 코드가 올라가서 5% 유저를 상대로 간 보고 있는 신상 서버 |
| **관측 시스템 (CCTV)** | 신상 서버에서 에러 뿜뿜하는지 눈에 불을 켜고 째려보는 프로메테우스 |

#### 한줄 요약

- 라우터(문지기)가 유저를 구버전과 신버전으로 쪼개 보내고, 감시 카메라가 터지는지 감시한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 카나리 분석(ACA, Automated Canary Analysis)**: 카나리에 5% 트래픽 줬을 때 사람이 로그 보며 쫄지 않고, 봇이 알아서 "에러 치솟네? 롤백!"을 판단해 주는 기능이다.

</details>

```text
[ 카나리 배포 십자포화 흐름 ]
┌──────────────────────────────┐
│ 신규 버전(V2) 빌드 완료      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. V2 컨테이너 배포 (Pod 띄움)│
│ (아직 유저 트래픽은 0%)      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 트래픽 5% 찔끔 흘림       │
│ (카나리 유저들 마루타 투입)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 봇이 에러율 팩트 체크     │
│ (정상이면 5% ➔ 50% ➔ 100%)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. V1(구버전) 깔끔하게 삭제  │
│ (100% 배포 성공!)            │
└──────────────────────────────┘
```

### 동작 원리

1. V2 배포: 새 버전 컨테이너를 띄움 (이땐 아무도 접속 못 함).
2. 트래픽 분사: 라우터 살짝 열어서 유저 5%만 V2로 보냄.
3. ACA 팩트 체크: V2에서 터지는 에러율이 V1보다 높은지 봇이 비교함.
4. 롤백 or 고: 에러 터지면 5% 뺏어서 롤백하고, 멀쩡하면 100%까지 올림.
5. 정리: 트래픽 100% 다 넘겼으면 놀고 있는 V1(구버전) 서버 죽임.

#### 한줄 요약

- 5% 흘리고 팩트 체크 $\to$ 멀쩡하면 올리고 $\to$ 터지면 바로 뺀다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **롤링 vs 블루-그린 vs 카나리**: 롤링은 서버 하나씩 교체하는 노가다, 블루-그린은 똑같이 복사해 놓고 1초 만에 팍 내리는 돈지랄, 카나리는 찔끔 간 보는 소심쟁이(하지만 젤 안전) 방식이다.

</details>

| 비교 항목 | **Rolling (노가다 배포)** | **Blue-Green (돈지랄 상남자)** | **Canary (안전빵 소심쟁이)** |
|:---|:---|:---|:---|
| 배포 방식 | 1대씩 죽이고 새 서버로 교체 | 새 서버 100% 다 띄우고 **스위치 팍 교체** | **5% $\to$ 20% $\to$ 100%** 찔끔찔끔 교체 |
| 자원 오버헤드 | 서버 1대 분량만 더 필요 | **서버가 정확히 2배 필요 (유지비 폭발)** | 소량의 카나리 서버만 추가 |
| 버전 꼬임 | 배포 도중 **구/신버전 짬뽕됨** | **짬뽕 안 됨. 전환 전엔 100% 구버전만** | **의도적으로 구버전 95% / 신 5% 공존** |
| 롤백 스피드 | 하나씩 역순 교체라 암 걸림 | **라우터 스위치 돌리면 1초 컷** | **카나리한테 주던 5% 뺏으면 1초 컷** |

#### 한줄 요약

- 돈 많으면 블루-그린으로 한방에 가고, 무조건 안전해야 하면 카나리로 간 본다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **확장-축소 패턴(Expand-Contract Pattern)**: 배포 중에 DB 컬럼을 바꾸면 구버전 앱이 터지니까, "컬럼 추가(확장) $\to$ 배포 $\to$ 옛날 컬럼 삭제(축소)"로 조심스럽게 DB를 바꾸는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 블루-그린 돌렸는데 DB 꼬여서 구버전 앱 터짐 | DB는 엎지 말고 **Expand-Contract (2단계 변경)** 적용 | 배포 중 DB 트랜잭션 에러 차단 |
| 블루-그린 하려면 서버 2배로 필요한데 돈 없음 | 100% 넘어가자마자 **구버전(Blue) 즉시 삭제(Scale-in)** | 클라우드 인프라 비용 폭발 방지 |
| 카나리 배포했는데 유저 세션 날아가서 로그아웃됨| 세션을 서버에 두지 말고 **Redis로 외부화 (Stateless)** | 배포하든 말든 유저 로그인 안 풀림 |

#### 한줄 요약

- 배포할 때 DB는 절대 한 번에 갈아엎지 말고, 로그인 안 풀리게 세션은 밖으로 빼놔라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **무장애 배포 선택 기준(Zero-Downtime Deployment Standards)**: 우리 회사가 돈이 남아도는지, 에러를 1초도 용납 못 하는지 각 재서 배포 전략을 정하는 잣대이다.

</details>

- **무장애 배포 선택 기준** 원칙에 따라, 유저 타격이 치명적이면 **Canary**, 서버 빵빵하고 빠른 롤백 원하면 **Blue-Green** 채택 기조 확립함

#### 한줄 요약

- 사용자는 모르게 서버를 통째로 갈아치우는 클라우드 시대의 마술이다.
