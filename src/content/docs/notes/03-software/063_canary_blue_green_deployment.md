## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Canary 및 Blue-Green(Canary & Blue-Green)**: 소수 사용자에게 트래픽을 점진 노출(Canary, 1%→10%→100%)하거나 완전한 동일 환경 2개를 구축해 로드밸런서로 일괄 전환(Blue-Green)하는 무중단 배포 기법.
- **인플레이스 다운타임 및 롤백 불가(In-Place Downtime & Rollback Failure)**: 구버전 서버를 직접 중단하고 새 바이너리를 올리는 과정에서 서비스가 끊기고 오류 시 복구 시간이 장기화되는 문제.

</details>

- 정의/개념: 무중단 릴리스를 달성하기 위해 **트래픽 비율을 점진 조절(Canary)하거나 완전 동일한 이중 환경을 스위칭(Blue-Green)** 하는 제로 다운타임 배포 전략
- 배경/필요성: 인플레이스(In-place) 덮어쓰기 배포 시 발생하는 **서비스 중단 시간(Downtime) 및 장애 발생 시 즉각 롤백 불가 한계** 직면

#### 한줄 요약

- 카나리는 트래픽을 점진적으로 전환하여 장애 파급 범위를 최소화하고, 블루-그린은 병렬 환경 전환으로 즉각 롤백을 지원

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **장애 파급 범위(Blast Radius)**: 배포 중 결함 발생 시 영향을 받는 사용자·서비스의 범위로, 카나리 배포는 초기 5%로 파급 범위를 제한.
- **라우팅 스위치(Routing Switch)**: 로드밸런서·Ingress Controller가 트래픽 비율을 조정하여 구버전·신버전으로 유저를 선택적으로 라우팅하는 제어 지점.

</details>

- 카나리: **장애 파급 범위를 초기 1~5%로 제한**하여 위험 최소화 배포
- 블루-그린: 구버전(Blue)·신버전(Green) 병렬 운영 후 **라우터 스위치 즉시 전환**
- 두 방식 모두 L4/L7 라우터 스위치 조작으로 **즉각 롤백** 가능

#### 한줄 요약

- 카나리는 점진 노출로 파급 범위를 최소화하고, 블루-그린은 병렬 환경으로 즉각 전환·롤백을 지원

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Ingress Controller / Service Mesh**: 트래픽 비율(예: Blue 95% / Canary 5%)을 제어하는 L7 라우팅 컴포넌트.

</details>

```text
[ 카나리 배포 구조 ]
사용자 트래픽 100%
   │
L7 라우터 (Ingress/Service Mesh)
   ├─ 95% → Blue(V1, 기존 운영 버전)
   └─ 5%  → Canary(V2, 신규 버전)

[ 블루-그린 배포 구조 ]
사용자 트래픽 100%
   │
L7 라우터 (전환 전) → Blue(V1) [100%]
L7 라우터 (전환 후) → Green(V2) [100%]
```

선의 의미: 가지(`├─`, `└─`)는 라우터가 트래픽을 Blue/Canary로 분배하는 비율, 블루-그린의 화살표 전환은 스위치 조작 전후 관계

| 구성요소 | 책임 |
|:---|:---|
| **배포 제어기(ArgoCD)** | 신버전 배포·트래픽 비율 조정·결함 감지 시 롤백 실행 |
| **트래픽 라우터(Ingress)** | 트래픽 비율 기반 Blue/Green/Canary 라우팅 |
| **Blue(기존 버전)** | 현재 운영 중인 안정 버전 |
| **Green/Canary(신버전)** | 새로 배포된 버전·점진 검증 또는 즉시 전환 대상 |
| **관측 시스템(Prometheus)** | 신버전의 에러율·지연 시간·CPU 등 가드레일 지표 감시 |

#### 한줄 요약

- 라우터가 트래픽을 Blue/Canary로 분배하고 관측 시스템이 신버전 이상 여부를 감시

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 카나리 분석(ACA, Automated Canary Analysis)**: 카나리 트래픽의 지표를 기준 버전과 자동으로 비교하여 롤백 또는 트래픽 확대를 자동 결정하는 기능.

</details>

```text
[ 카나리 배포 흐름 ]
1. 신버전(V2) 컨테이너 기동 (트래픽 미노출)
   │
2. 트래픽 5% → V2로 라우팅 (카나리 사용자 검증)
   │
3. ACA: V2 에러율·지연 시간을 V1과 자동 비교
   ├─ 정상: 5% → 20% → 100% 단계적 확대
   └─ 이상: 5% 트래픽 회수 → 즉각 롤백
   │
4. 100% 전환 완료 후 V1(구버전) 종료

[ 블루-그린 배포 흐름 ]
1. Green(V2) 환경 구성 (Blue와 동일 규모)
2. 스모크 테스트로 Green 정상 동작 확인
3. 라우터 스위치 조작: 트래픽 100% Blue → Green 즉시 전환
4. 이상 감지 시: 스위치 역전으로 Blue 즉각 복구
5. 안정 확인 후 Blue 환경 종료
```

**동작 원리** 1. **카나리**: 신버전을 소수 사용자에게 노출하고 ACA로 기준 버전 대비 지표를 비교하여 이상 시 즉각 롤백
2. **블루-그린**: 동일 규모의 Green 환경을 병렬로 구성하고 라우터 스위치 조작으로 즉시 전환·역전 롤백

#### 한줄 요약

- 카나리는 점진 노출·ACA 자동 판정으로, 블루-그린은 병렬 환경·스위치 전환으로 무장애 배포 실현

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **롤링·블루-그린·카나리 비교**: 롤링은 순차 교체, 블루-그린은 병렬 전환, 카나리는 점진 노출로 무장애 배포를 구현하는 세 가지 전략.

</details>

| 구분 | 롤링(Rolling) | 블루-그린 | 카나리 |
|:---|:---|:---|:---|
| 적용 기준 | 자원 최소화·단순 배포 | 빠른 전환·즉각 롤백 필요 | 최소 위험·점진 검증 필요 |
| 핵심 특징 | 인스턴스 순차 교체 | 병렬 환경 즉시 스위치 전환 | 소수 트래픽 점진 확대 |
| 자원 오버헤드 | 소규모 추가 | **현재의 2배 규모** | 카나리 인스턴스 소규모 추가 |
| 배포 중 버전 혼재 | 구/신 버전 동시 운영 | 전환 전 단일 버전 | **의도적 구/신 동시 운영** |
| 롤백 속도 | 역순 교체(느림) | **스위치 역전(즉각)** | **카나리 트래픽 회수(즉각)** |

#### 한줄 요약

- 자원 여유·빠른 롤백 필요 시 블루-그린, 최소 위험·점진 검증 필요 시 카나리 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **확장-축소 패턴(Expand-Contract Pattern)**: DB 스키마 변경 시 신규 컬럼 추가(확장)→신버전 배포→구 컬럼 제거(축소)의 순서로 구버전과의 하위 호환을 유지하는 마이그레이션 전략.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 배포 중 DB 스키마 변경으로 구버전 앱 장애 발생 | **Expand-Contract 패턴** 기반 하위 호환 유지하며 단계적 스키마 변경 | 배포 중 DB 호환성 보장 |
| 블루-그린 배포 시 2배 인프라 비용 발생 | 전환 완료 즉시 **Blue 환경 Scale-in** 수행 | 클라우드 인프라 비용 최소화 |
| 카나리 배포 중 사용자 세션 손실 발생 | 세션을 **Redis 등 외부 저장소** 기반 분리(Stateless 설계) | 배포 중 세션 유지 |

#### 한줄 요약

- DB 변경은 Expand-Contract로, 블루-그린 비용은 즉시 Scale-in으로, 세션 손실은 Redis 외부화로 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **무장애 배포 전략 선택 기준**: 인프라 비용 허용 수준·롤백 속도 요구·장애 파급 허용 범위를 기준으로 카나리·블루-그린·롤링을 결정하는 판단 기준.

</details>

- 사용자 영향을 최소화한 안전한 점진 검증이 필요하면 **카나리**, 즉각 전환과 빠른 롤백이 필요하면 **블루-그린** 선택

#### 한줄 요약

- 장애 파급 최소화에는 카나리, 즉각 전환·롤백에는 블루-그린을 선택하여 무장애 배포를 실현
