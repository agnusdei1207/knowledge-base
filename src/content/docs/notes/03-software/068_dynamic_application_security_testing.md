## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **동적 애플리케이션 보안 테스트(Dynamic Application Security Testing, DAST)**: 실행 중인 서비스에 공격 요청을 보내 외부에서 관찰되는 취약 반응을 찾는 시험이다.
- **실제 공격 성공**: 설정•인증•실행 환경을 포함한 조건에서 공격이 유효한 결과를 만드는 상태이다.

</details>

- 정의/개념: **DAST** 는 실행 중인 애플리케이션에 외부 공격 요청을 보내 응답과 동작을 관찰하여 실제 노출 취약점을 찾는 동적 보안 시험 기법
- 배경/필요성: 코드 분석만으로는 설정•인증을 포함한 **실제 공격 성공 확인 불가**

#### 한줄 요약

- 실행 서비스 공격 요청 기반 **외부 취약 반응 검증**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **블랙박스 실행 검사**: 내부 코드 없이 외부 입력과 출력으로 실행 서비스의 보안을 검증하는 방식이다.
- **실제 취약 반응 확인**: 서버 설정과 인증을 포함한 환경에서 공격 결과를 직접 관찰하는 활동이다.
- **검사 누락**: 크롤러가 찾지 못한 경로나 권한이 시험 대상에서 빠지는 상태이다.

</details>

- 외부 공격자 관점의 **블랙박스 실행 검사**
- 서버 설정•인증을 포함한 **실제 취약 반응 확인**
- 탐색하지 못한 경로와 권한은 **검사 누락**

#### 한줄 요약

- 실제 공격 검증과 **탐색 경로•권한 누락 한계**

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **크롤러(Crawler)**: 링크•폼•경로를 따라가며 검사할 공격 표면을 수집하는 구성요소이다.
- **공격 페이로드(Attack Payload)**: 취약 반응을 유도하려고 입력점에 삽입하는 공격 데이터이다.
- **인증 컨텍스트(Authentication Context)**: 로그인 상태•권한•세션을 유지하는 테스트 정보이다.
- **취약점 보고서(Vulnerability Report)**: 공격 요청•서비스 응답•재현 절차를 연결한 증거이다.

</details>

```text
             [크롤러]
                 \
              [공격 엔진] -- [응답 분석기] -- [취약점 보고서]
                 /
         [인증 컨텍스트]
```

선의 의미: 공격 엔진은 크롤러가 수집한 공격 표면과 인증 컨텍스트를 함께 사용하고, 응답 분석기는 공격 결과를 판정해 취약점 보고서의 증거를 구성한다.

| 구성요소 | 책임 |
|:---|:---|
| 크롤러 | **경로•폼•매개변수** 공격 표면 수집 |
| 공격 엔진 | 입력점별 **공격 페이로드** 주입 |
| 인증 컨텍스트 | **세션•권한별 접근 상태** 유지 |
| 응답 분석기 | **상태•본문•응답 시간** 의 취약 징후 판정 |
| 취약점 보고서 | **요청•응답•재현 절차** 증거 제공 |

#### 한줄 요약

- 탐색•공격•인증•응답•**보고 구조**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **공격 표면(Attack Surface)**: 외부에서 접근 가능한 경로•매개변수•기능의 집합이다.
- **공격 엔진(Attack Engine)**: 입력점별로 공격 페이로드와 인증 상태를 조합해 요청하는 구성요소이다.
- **상태 코드(Status Code)**: 공격 요청의 처리 결과를 나타내는 응답 코드다.
- **응답 본문(Response Body)**: 공격 결과의 출력 데이터를 담은 응답 내용이다.
- **응답 시간(Response Time)**: 공격 요청부터 응답까지 걸린 시간이다.
- **허용 범위 내 공격 표면 탐색**: 승인된 경로에서 링크•폼•기능을 수집하는 동작이다.
- **경로•입력점 분류**: 수집한 표면에서 변조할 매개변수와 기능을 공격 엔진에 제공하는 동작이다.
- **공격 페이로드•인증 세션 전송**: 역할별 입력점에 공격 데이터를 넣은 요청을 보내는 동작이다.
- **취약 반응•재현 증거 판정**: 상태 코드•본문•시간을 분석해 실제 취약 반응과 재현 절차를 기록하는 동작이다.

</details>

```text
[허용 범위•인증 컨텍스트]
           |
           v
+----------------------------------+
| 1. 허용 범위 내 공격 표면 탐색  |
+----------------------------------+
           |
           v
+----------------------------------+
| 2. 경로•입력점 분류             |
+----------------------------------+
           |
           v
+----------------------------------+
| 3. 공격 페이로드•인증 세션 전송 |
+----------------------------------+
           |
           v
+----------------------------------+
| 4. 취약 반응•재현 증거 판정     |
+----------------------------------+
           |
      +----+----+
      | 취약    | 정상
      v         v
[보고•수정] [범위•페이로드 보강]
```

**동작 원리**

1. **허용 범위 내 공격 표면 탐색**: 화면•경로 수집
2. **경로•입력점 분류**: 공격할 매개변수•기능 제공
3. **공격 페이로드•인증 세션 전송**: 권한별 변조 요청
4. **취약 반응•재현 증거 판정**: 응답 증거 보존

> 요약: 범위 내 공격 표면에 실제 요청을 보내 외부에서 관찰되는 취약 반응을 검증

#### 한줄 요약

- 범위•권한별 공격과 **취약 반응 증거 판정**

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **정적 애플리케이션 보안 테스트(Static Application Security Testing, SAST)**: 소스와 바이너리의 내부 경로에서 결함을 찾는 테스트다.

</details>

| 애플리케이션 보안 테스트 | DAST | SAST |
|:---|:---|:---|
| 적용 기준 | 운영 유사 환경의 **공격 가능성 검증** | 개발 단계의 **코드 결함 조기 탐지** |
| 핵심 특징 | 실행 서비스 **요청•응답 분석** | 소스•바이너리 **내부 경로 분석** |
| 한계 | 코드 위치 불명•**탐색 경로 누락** | 실행 맥락 부재•**오탐** |

> 요약: DAST는 공격 가능성을 확인하고 SAST는 코드 원인을 추적

#### 한줄 요약

- 공격 가능성은 DAST, 코드 원인은 **SAST**

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능을 정해진 요청•응답 계약으로 호출하게 하는 인터페이스이다.
- **API 명세(API Specification)**: 외부 호출 경로•입력•응답 형식을 정의한 문서이다.
- **프록시 기록(Proxy Record)**: 중계 지점에서 실제 요청•응답을 수집한 통신 기록이다.
- **요청 식별자(Request Identifier)**: 외부 요청과 내부 로그•코드 실행을 연결하는 고유 값이다.
- **스테이징 환경(Staging Environment)**: 운영과 유사하되 실제 사용자 영향 없이 보안 검증을 수행하는 시험 환경이다.
- **수동 경로(Manual Path)**: 자동 크롤러가 찾지 못하는 비공개 API•업무 흐름을 테스터가 직접 정의한 검사 경로이다.
- **역할별 계정(Role-specific Account)**: 서로 다른 권한으로 준비한 시험 계정이다.
- **권한 전환(Privilege Switching)**: 같은 기능을 역할별 세션으로 검사하는 방식이다.
- **격리 환경(Isolated Environment)**: 운영과 분리해 공격 시험을 수행하는 환경이다.
- **요청 제한(Request Limit)**: 공격 요청의 속도와 수를 제한하는 통제다.
- **시험 데이터(Test Data)**: 공격 시험 뒤 폐기할 수 있는 전용 데이터다.
- **원본 요청 재현(Baseline Replay)**: 공격 변조 전 정상 요청과 결과를 다시 비교하는 절차다.
- **수동 검토(Manual Review)**: 사람이 실제 취약 반응인지 확인하는 절차다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 링크 탐색만으로 숨은 API•비공개 경로 누락 | **API 명세•프록시 기록•수동 경로** 추가 | **숨은 경로 검사 범위** 확대 |
| 단일 계정 검사로 역할별 권한 취약점 누락 | **역할별 계정•권한 전환** 구성 | **권한별 취약점 누락** 방지 |
| 파괴적 요청이 운영 데이터•가용성을 훼손 | **격리 환경•요청 제한•시험 데이터** 사용 | **데이터•가용성 훼손** 방지 |
| 일반 오류 응답을 취약 반응으로 오판 | **원본 요청 재현•수동 검토** | **취약 판정 신뢰도** 향상 |
| 외부 응답만으로 취약 코드 위치 추적 곤란 | **요청 식별자•로그•SAST** 연계 | **수정 위치 추적성** 확보 |

> 적용 사례: 운영 유사 환경에서 데이터베이스 삽입 공격의 노출•오류 반응 검증

#### 한줄 요약

- 명세•역할•격리•요청 추적 기반 **DAST 범위 보강**

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **권한(Privilege)**: DAST의 역할별 탐색 범위를 정하는 기준이다.
- **운영 영향(Operational Impact)**: DAST의 안전 통제 강도를 정하는 기준이다.
- **DAST 범위**: 동적 공격 검사를 수행할 경로•역할•기능•환경의 경계이다.

</details>

- **공격 표면•권한•운영 영향** 에 따라 DAST 범위를 결정

#### 한줄 요약

- 공격 표면•권한•운영 영향 기반 **DAST 범위**
