## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **동적 보안 분석(DAST, Dynamic Application Security Testing)**: 코드를 안 까보고, 쌩으로 돌아가고 있는 웹사이트에다가 해커처럼 미친 듯이 해킹 공격(페이로드)을 날려보면서 "이거 뚫리네?" 하고 팩트 체크하는 샌드백 테스트이다.
- **블랙박스 보안 테스트(Black-box Security Testing)**: 소스코드 구조 따윈 1도 모르고, 걍 외부에서 회원가입 폼이나 검색창에 XSS 스크립트를 쑤셔 넣어보는 무식하지만 확실한 관점이다.
- **OWASP ZAP / Burp Suite**: 해커들(그리고 모의해킹 컨설턴트들)이 웹사이트를 자동으로 크롤링하고 수천 개의 공격 패턴을 연사로 쏴주는 국룰 공격 자동화 봇이다.

</details>

- 정의: 구동 중인 실운영/Staging 환경의 웹앱 외부에 동적 모의 침투 공격을 쏴서 런타임 취약점 및 설정 오류를 팩트 폭행하는 **DAST**
- 배경: 정적 분석(SAST)만으로는 **서버 세팅 오류나 해커가 실제로 뚫을 수 있는지 여부**를 100% 장담할 수 없기 때문

#### 한줄 요약

- 코드 쳐다보는 짓 집어치우고, 진짜로 샌드백(서버)을 패보면서 뚫리는지 확인하는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제로 오탐 지향(False Positive 0% 지향)**: SAST처럼 예측만으로 헛소리(오탐)하지 않고, 실제로 공격해 보고 서버가 터지거나 DB 정보가 질질 새는 걸 두 눈으로 확인하니까 무조건 팩트다.
- **언어 독립성(No Source Code Needed)**: 앱을 자바로 짰든 파이썬으로 짰든 알 빠 아니고, 그냥 URL 엔드포인트만 열려있으면 앞뒤 안 가리고 공격할 수 있다.

</details>

- 소스코드 1도 안 보는 외부 공격자 뷰 **Black-box Testing**.
- 언어 독립적(**Language Agnostic**)이고 찌르면 팩트만 나오니 **오탐률(False Positive)**이 매우 낮음.
- 해킹 성공해도 "코드 몇째 줄이 문제냐?" 물어보면 라인 번호는 못 집어주는 게 한계.

#### 한줄 요약

- 헛소리(오탐)가 없고 팩트만 말하지만, 소스코드를 몰라서 코드 몇 줄인지 못 집어준다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **크롤러(Spider / Crawler)**: 해킹봇이 웹사이트에 접속해서 링크, 버튼, 숨겨진 폼까지 싹 다 클릭해 보며 "어디를 찌르면 아플까(공격 표면)" 목록을 탈탈 터는 선발대이다.

</details>

```text
[ DAST 십자포화 아키텍처 ]

[ 타겟 웹사이트 URL ]
         │
         ▼
  [ 스파이더 (URL 수집) ] ────▶ [ 인증 컨텍스트 (로그인 유지) ]
         │
         ▼
 [ 공격 페이로드 발사! ] ──▶ (SQLi, XSS 폭격)
         │
         ▼
[ 취약점 리포트 산출 (팩트) ]
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **크롤러 (Spider)** | 사이트 구석구석 돌아다니며 쑤실 구멍(URL, 폼, API) 리스트 뽑는 정찰병 |
| **공격 페이로드** | 찾은 구멍에다가 SQLi, XSS 독극물을 무자비하게 쑤셔 넣는 타격 부대 |
| **인증 컨텍스트** | "로그인 안 하면 못 들어감" 막힐까 봐, 세션/토큰 유지하며 안쪽 털어주는 열쇠 |
| **취약점 보고서** | "검색창에 이 스크립트 넣었더니 DB 털렸음" 하고 재현 증거 박제하는 성적표 |

#### 한줄 요약

- 스파이더가 구멍 찾고 $\to$ 페이로드가 때리고 $\to$ 뚫리면 보고서 쓰는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **패시브/액티브 스캔(Passive vs Active Scanning)**: 패시브는 트래픽 냄새만 맡으면서 보안 헤더 빠졌나 훈수 두는 거고, 액티브는 진짜로 서버 터뜨리는 공격 쿼리를 냅다 꽂아버리는 상남자 스캔이다.

</details>

```text
[ DAST 공격 십자포화 흐름 ]
┌──────────────────────────────┐
│ 샌드백 서버(Staging) 준비    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 타겟팅 및 인증 세팅       │
│ (로그인 아이디/비번 알려줌)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 거미줄 치기 (크롤링)      │
│ (공격할 URL 리스트 다 뽑음)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 무지성 액티브 스캔 발사   │
│ (수만 개의 페이로드 폭격)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 반응 체크 (터졌냐?)       │
│ (터진 놈만 팩트 폭행 리포트) │
└──────────────────────────────┘
```

### 동작 원리

1. 환경 세팅: 엉뚱한 사이트 털면 철창 가니까, 합의된 타겟 URL과 로그인 권한을 먹임.
2. 공격 표면 탐색: 크롤러가 뽈뽈 돌아다니며 폼이랑 파라미터 싹 다 긁어옴.
3. 페이로드 주입: 긁어온 파라미터마다 준비된 해킹 텍스트(독극물)를 연사로 꽂음.
4. 반응 판정: 에러 페이지 뿜거나 5초 딜레이 걸리면 "오예 뚫렸다" 판정함.
5. 보고서: "이렇게 쏘면 뚫림" 하고 친절하게 재현 가이드 적어줌.

#### 한줄 요약

- 타겟 잡고 $\to$ 크롤링 돌리고 $\to$ 미친 듯이 쏘고 $\to$ 에러 뿜으면 박제한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대화형 분석(IAST, Interactive Application Security Testing)**: SAST(까보기)와 DAST(때리기)를 합친 혼종으로, 앱 속에 스파이를 심어놓고 밖에서 때리면 "어 방금 45번 줄 터졌다!" 중계해 주는 사기 기법이다.

</details>

| 비교 항목 | **SAST (정적, MRI 검사)** | **DAST (동적, 샌드백 검사)** | **IAST (대화형, 내부 스파이)** |
|:---|:---|:---|:---|
| 테스트 관점 | 안에서 뼈대(소스)만 뚫어지게 봄 | **밖에서 쌩으로 서버를 두들겨 팸** | **밖에서 패면 안에서 스파이가 중계함** |
| 코드 위치 | **"45번 줄 빵꾸" 팩폭 가능** | "URL은 아는데 코드는 모름" | **"45번 줄 빵꾸" 팩폭 가능** |
| 실행 필요 | 코드만 있으면 됨 (서버 불필요) | **살아 숨 쉬는 서버(Staging) 필수**| **서버도 띄우고 스파이도 심어야 함** |
| 오탐/미탐 | 안 돌려봐서 헛소리(오탐) 심함 | **실제 뚫린 거라 오탐 거의 없음** | 오탐 거의 없고 위치도 알려줌 (사기캐) |

#### 한줄 요약

- 코드 까는 건 SAST, 서버 때려보는 건 DAST, 둘 다 하는 건 IAST다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **실운영 위험(Production Risk)**: 생각 없이 운영 서버에 DAST 돌렸다가, 봇이 회원 탈퇴 버튼 누르고 다녀서 DB 싹 다 날려 먹는 대형 참사이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 생각 없이 운영 DB 털었다가 데이터 파괴됨 | 무조건 **완벽 격리된 Staging 환경**에서 더미 데이터로 스캔 | 사장님한테 끌려가는 사태 방지 |
| React 같은 SPA 앱은 크롤러가 링크 못 찾아 길 잃음 | 렌더링 다 해주는 **Headless Browser (Puppeteer)** 기반 크롤러 투입 | 삐까뻔쩍한 프론트엔드 구석구석 털기 |
| 10시간씩 걸려서 CI 파이프라인 정지됨 | 핵심 API만 터는 **기준선 검사**와 주말 **예약 스캔**으로 쪼갬 | CI 속도 챙기면서 보안도 챙김 |

#### 한줄 요약

- 라이브 서버에 쐈다간 회사 망하니까 무조건 Staging에서 쏘고, 너무 오래 걸리니까 주말에 돌려라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DAST 도입 수립 기준(DAST Adoption Standards)**: 우리 서버가 스캔 버틸 맷집이 있는지, SPA 크롤링이 되는 툴인지 각 재서 도입하는 잣대이다.

</details>

- **DAST 도입 수립 기준** 원칙에 따라, 소스코드 빵꾸는 **SAST/IAST**로 찾고, "해커가 실제로 뚫을 수 있냐?"는 **DAST** 팩트 폭행으로 증명하는 기조 확립함

#### 한줄 요약

- SAST가 "너 아플 거 같아"라면, DAST는 "한 대 맞아보니 진짜 아프지?"를 증명하는 거다.
