## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스레싱(Thrashing)**: 램(RAM)이 꽉 차서 하드디스크랑 데이터를 미친 듯이 스왑(Swap)하느라, 정작 CPU는 연산은 안 하고 데이터 배달만 기다리다가 시스템이 멈춰버리는 붕괴 현상이다.
- **워킹 셋(Working Set)**: 프로세스가 방금 전까지 미친 듯이 썼고, 앞으로도 당분간 계속 찾을 게 뻔해서 무조건 램에 올려놔야 하는 핵심 페이지 뭉치이다.
- **메이저 페이지 폴트(Major Page Fault)**: 찾으려는 데이터가 램에 없어서, 느려 터진 하드디스크(스왑 영역)까지 가서 긁어오느라 시간이 멈추는 최악의 캐시 미스이다.
- **스왑 대기(Swap Wait)**: 스레싱이 터져서 모든 프로세스가 하드디스크에서 자기 데이터가 올라오기만 목 빠지게 기다리며 줄 서 있는 좀비 상태이다.

</details>

- 정의: 가용 물리 메모리 부족으로 빈번한 페이지 교체(Swap I/O)가 폭증하여, CPU가 연산은 안 하고 입출력만 기다리다 이용률이 추락하는 **스레싱(Thrashing)**
- 배경: 멀티태스킹을 한답시고 프로그램을 너무 많이 띄워서, 각 프로그램이 먹을 **프레임 할당량**이 워킹 셋보다 쪼그라들었기 때문

#### 한줄 요약

- 프로그램들을 램에 너무 많이 쑤셔 넣어서, CPU가 연산은 안 하고 하드디스크 스왑만 하다가 뻗는 붕괴 현상이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다중프로그래밍 정도(Degree of Multiprogramming, DOM)**: CPU를 나눠 쓰겠다고 메모리에 한꺼번에 쑤셔 넣고 돌리는 프로그램의 총개수이다.
- **페이지 폴트 빈도(Page Fault Frequency, PFF)**: "디스크 너무 자주 긁으면 메모리 더 주고, 안 긁으면 뺏어라" 하고 폴트 횟수에 상하한선을 두고 메모리를 뺏고 주는 동적 조절 기법이다.

</details>

- 프로그램 개수(**DOM**)를 막 늘리다 보면 임계점을 넘는 순간 CPU 이용률과 스루풋이 절벽으로 다이빙함.
- 빈번한 **메이저 페이지 폴트**로 인해 디스크 I/O 대기열이 터져버림.
- **워킹 셋(Working Set)** 단위로 메모리를 보장하거나, **PFF(페이지 폴트 빈도)**로 멱살 잡고 프레임을 할당해 줘서 스레싱을 막음.

#### 한줄 요약

- 다중프로그래밍이 선을 넘으면 폴트가 폭증하고 CPU가 놀게 되며, 이를 워킹 셋과 PFF로 막아낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워킹 셋 윈도우(Working Set Window, Δ)**: "최근 10초 동안 뭐 썼냐?" 할 때 그 10초에 해당하는, 워킹 셋을 계산하기 위해 과거를 훑어보는 감시 시간 간격이다.
- **상주 집합(Resident Set)**: 가상 메모리 말고 진짜 물리 메모리(DRAM)에 떡하니 자리 잡고 알박기 중인 페이지들의 실제 집합이다.

</details>

```text
[ 스레싱 방어 십자포화 아키텍처 ]
┌─────────────────────────────────────────┐
│            상주 집합 관리자             │
│         (물리 메모리 알박기 통제)        │
├────────────────────┬────────────────────┤
│   워킹 셋 추적기   │ 페이지 폴트 감시기 │
│(윈도우 훑어서 짐 쌈)│  (디스크 긁는 빈도 잼)│
└─────────┬──────────┴──────────┬─────────┘
          ▼                     ▼
┌─────────────────────────────────────────┐
│               부하 제어기               │
│  (스레싱 터지면 프로그램 쫓아냄(Swap))   │
└─────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| 워킹 셋 추적기 | 최근 **워킹 셋 윈도우($\Delta$)** 동안 놈이 무슨 페이지를 썼는지 감시해서 필수 메모리 양을 계산하는 탐정 |
| 상주 집합 관리자 | 물리 메모리에 **상주 집합(Resident Set)**을 꽂아주고, 모자라면 LRU 돌려서 쫓아내는 건물주 |
| 페이지 폴트 감시기 | 놈이 얼마나 자주 하드디스크를 긁는지(**PFF**) 상/하한선을 재는 감시 카메라 |
| 부하 제어기 | 감시기가 스레싱을 포착하면, 멱살 잡고 프로그램 하나를 디스크로 내쫓아서(**DOM 축소**) 메모리 공간을 확보하는 일진 |

#### 한줄 요약

- 워킹 셋과 PFF를 감시하다가, 스레싱 조짐이 보이면 제어기가 프로그램 하나를 내쫓아 메모리를 번다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스레싱 연쇄 악순환(Thrashing Cascade Loop)**: 메모리 모자람 $\to$ 디스크 긁음 $\to$ CPU 놂 $\to$ OS가 "CPU 노네? 프로그램 더 올려!" $\to$ 메모리 더 모자람의 미친 죽음의 굴레이다.

</details>

```text
[ 스레싱 죽음의 연쇄 악순환 흐름 ]
┌──────────────────────────────┐
│ 1. 필수 메모리(워킹 셋) 부족 │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 메이저 페이지 폴트 폭증   │◀─────────────┐
│ (하드디스크 미친 듯이 긁음)  │              │
└──────────────┬───────────────┘              │
               ▼                              │
┌──────────────────────────────┐              │
│ 3. 디스크 대기 폭발, CPU 놂  │              │
│ (CPU 이용률 나락 감)         │              │
└──────────────┬───────────────┘              │
               ├─ 스레싱 눈치챔 ─▶ [프로그램 강제 정지, DOM 축소]
               │ OS가 오판함 (CPU가 남는 줄 암) │
               ▼                              │
┌──────────────────────────────┐              │
│ 4. 다중프로그래밍(DOM) 증가  │              │
│ (프로그램을 메모리에 더 꽂음) │              │
└──────────────┬───────────────┘              │
               ▼                              │
┌──────────────────────────────┐              │
│ 5. 남은 메모리마저 개박살 남 │──────────────┘
│ (악순환 반복)                │
└──────────────────────────────┘
```

### 동작 원리

1. 필수 메모리 부족: 가용 프레임이 워킹 셋보다 적어져서 필요한 데이터가 램에 없음.
2. 폴트 및 교체 폭증: 데이터를 디스크에서 퍼오느라(**페이지 폴트**) 스왑(Swap) I/O가 터짐.
3. CPU 이용률 저하: 다들 디스크만 기다리니까 CPU가 할 일이 없어서 놀게 됨.
4. OS 오판 및 DOM 증가: OS가 "어? CPU가 노네? 일 더 시켜!" 하고 **DOM**을 올려서 프로그램을 더 쑤셔 넣음.
5. 악순환 및 프레임 축소: 모자란 메모리를 새로 온 놈이랑 나눠 먹느라 파이가 더 줄어들고 지옥문이 열림.

#### 한줄 요약

- 폴트 터짐 $\to$ CPU 놂 $\to$ OS가 프로그램 더 올림 $\to$ 폴트 더 터짐의 죽음의 굴레다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로그램 켤 때 램에 다 올리지 않고, 당장 필요한 페이지만 "요구"할 때 그때그때 디스크에서 퍼오는 기본 가상 메모리 기법이다.

</details>

| 비교 항목 | 정상 요구 페이징 (Demand Paging) | **스레싱 붕괴 상태 (Thrashing)** |
|:---|:---|:---|
| 페이지 폴트 발생률 | 프로그램 켤 때만 반짝하고 금방 안정됨 | 디스크 긁느라 **재참조 폴트**가 끝없이 폭주함 |
| CPU 이용률 | 100% 꽉꽉 채워서 유용한 연산만 미친 듯이 함 | 0%에 수렴하며 다들 디스크 벤치에 누워서 잠만 잠 |
| 주요 시간 소비 | CPU가 명령어 돌리는 데 시간을 씀 | 하드디스크 헤드 움직이느라(**Swap I/O**) 시간 다 버림 |
| 해결책 | LRU 같은 교체 알고리즘 얌전히 돌리면 됨 | 프로그램 몇 개 멱살 잡고 쫓아내서(**DOM 축소**) 워킹 셋 파이를 확보해야 함 |

#### 한줄 요약

- 정상일 땐 CPU가 바쁘게 돌지만, 스레싱이 터지면 디스크 I/O만 하느라 CPU가 멈춰버린다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **씨그룹 메모리 리밋(cgroups Memory Limit)**: 리눅스에서 컨테이너(도커)가 램을 무한정 처먹고 스레싱 내는 걸 막으려고 멱살 잡고 캡(Cap)을 씌우는 기능이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| OS가 멀티태스킹 한답시고 프로그램 100개 띄우다가 램 터지고 **스레싱** 걸림 | **워킹 셋(Working Set)** 들이밀고 안 되면 놈들 강제 정지(**DOM 축소**)함 | 램 파이를 강제로 벌어서 I/O 지옥을 끊고 CPU 살려냄 |
| 한 놈이 메모리를 미친 듯이 할당해서 옆에 얌전한 놈 램까지 다 뺏어 먹음 | **PFF(페이지 폴트 빈도)** 재서 자주 안 긁는 놈 램 뺏어서 몰아줌 | 메모리 돼지한테 프레임 더 주고 잉여 램 회수해서 밸런스 패치 |
| 도커 컨테이너 하나가 노드 램 다 쳐먹고 OS 전체를 스레싱 내버림 | 리눅스 **cgroups Memory Limit** 박고 넘치면 OOM 킬러로 죽여버림 | 컨테이너 하나가 미쳐 날뛰어도 노드 전체가 터지는 걸 철통 방어 |

#### 한줄 요약

- 프로그램 강제 종료로 램을 벌고, PFF로 파이를 나누며, 컨테이너는 cgroups로 멱살을 잡아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스레싱 방지 관리 기준(Thrashing Prevention Criteria)**: 폴트 빈도(PFF), 멀티태스킹 개수(DOM), 컨테이너 한도(cgroups)를 조율해서 CPU가 노는 꼴을 막는 잣대이다.

</details>

- **스레싱 방지 관리 기준** 원칙에 따라, 구형 OS는 **PFF/워킹 셋**으로 멱살 잡고, 최신 컨테이너 환경은 **cgroups 메모리 격리** 채택 기조 확립함

#### 한줄 요약

- OS 레벨에서는 PFF와 DOM 축소로 막고, 현대의 클라우드 환경에서는 cgroups로 메모리를 격리해야 한다.
