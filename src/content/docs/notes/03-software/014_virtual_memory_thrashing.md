## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **프로세스 스레싱(Process Thrashing)**: 페이지 교체가 유효한 프로세스 실행을 압도하는 가상 메모리 성능 붕괴 상태이다.
- **워킹 셋(Working Set)**: 최근 구간에 프로세스가 반복 참조한 페이지 집합이다.

</details>

- 정의/개념: **프로세스 스레싱**은 워킹 셋이 할당 프레임을 넘어 페이지 교체 작업이 유효한 실행을 압도하는 **가상 메모리 성능 붕괴 상태**이다.
- 배경/필요성: 프로세스별 워킹 셋을 무시한 프레임 배분으로 **교체 I/O•CPU 유휴가 증가한다**.

#### 한줄 요약

- 워킹 셋 미수용으로 **페이지 교체가 실행을 압도**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **페이지 폴트율**: 관찰 구간의 페이지 참조 중 비상주 페이지 예외가 발생한 비율이다.
- **다중프로그래밍 정도(Degree of Multiprogramming)**: 동시에 메모리에 둔 실행 프로세스 수이다.

</details>

| 프레임 수용 상태 | 워킹 셋 미수용 | 수용 경계 | 워킹 셋 수용 |
|:---|:---|:---|:---|
| 페이지 폴트율 | 높음 | 급감 | 낮음 |

> 할당 프레임이 **워킹 셋**을 충족한 뒤 **페이지 폴트율** 감소 폭 축소

- **워킹 셋 미수용**으로 재참조 페이지 폴트 반복이 핵심이다.
- **페이지 교체 I/O 증가**로 CPU 이용률•처리량 저하된다.
- **다중프로그래밍 정도 증가**가 프레임 부족•처리량 붕괴를 증폭이 핵심이다.

#### 한줄 요약

- 프레임 부족이 **교체 I/O•CPU 유휴**를 연쇄 증폭이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **상주 집합(Resident Set)**: 프로세스가 물리 메모리에 보유한 프레임 집합이다.
- **부하 제어기(Load Controller)**: 폴트율과 CPU 이용률로 스레싱을 판정해 작업 수와 프레임 배분을 조정하는 구성요소이다.
- **워킹 셋 추적기(Working-set Tracker)**: 최근 참조 페이지로 필요 프레임을 추정하는 구성요소이다.
- **상주 집합 관리자(Resident-set Manager)**: 물리 프레임의 할당과 교체를 수행하는 구성요소이다.
- **페이지 폴트 감시기**: 프로세스별 폴트 빈도와 재참조 교체를 계측해 스레싱 징후를 탐지하는 구성요소이다.

</details>

```text
             [실행 프로세스]
                    |
            [워킹 셋 추적기]
                    |
           [상주 집합 관리자]
                    |
          [페이지 폴트 감시기]
                    |
              [부하 제어기]
```

선의 의미: 워킹 셋 추적기는 실행 프로세스의 필요 프레임을 추정해 상주 집합 관리자에 제공하고, 페이지 폴트 감시기와 부하 제어기는 할당 상태와 부하를 조정한다.

| 구성요소 | 책임 |
|:---|:---|
| 실행 프로세스 | **페이지 참조 생성** |
| 워킹 셋 추적기 | **필요 프레임 수 추정** |
| 상주 집합 관리자 | **프레임 할당•교체** |
| 페이지 폴트 감시기 | **반복 폴트 탐지** |
| 부하 제어기 | **작업 수•프레임 조정** |

#### 한줄 요약

- 워킹 셋•폴트율 기반 **프레임•작업 수 조정** 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **재참조 폴트 증가**: 워킹 셋 페이지가 퇴출된 뒤 다시 참조돼 폴트가 반복되는 단계이다.
- **교체 I/O 증가**: 퇴출과 재적재가 늘어 저장장치 작업이 증가하는 단계이다.
- **CPU 이용률 저하**: 프로세스가 페이지 입출력을 기다려 CPU 유효 실행이 줄어드는 단계이다.
- **다중프로그래밍 증가**: 낮은 CPU 이용률을 작업 부족으로 오판해 실행 프로세스를 늘리는 단계이다.
- **프로세스별 프레임 감소**: 추가 프로세스와 프레임을 나눠 워킹 셋 부족이 심해지는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 워킹 셋 > 할당 프레임       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 재참조 폴트 증가         │◀──────────────┐
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 2. 교체 I/O 증가            │               │
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 3. CPU 이용률 저하          │               │
└───────┬──────────────────────┘               │
        ├─ 스레싱 판정 ─▶ [작업 수 축소·프레임 재배분]
        │ 오판                                  │
        ▼                                       │
┌──────────────────────────────┐               │
│ 4. 다중프로그래밍 증가      │               │
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 5. 프로세스별 프레임 감소   │───────────────┘
└──────────────────────────────┘
```

**동작 원리**

- **1. 재참조 폴트 증가**: 퇴출 페이지의 반복 참조로 폴트 급증이다.
- **2. 교체 I/O 증가**: 페이지 퇴출•재적재 작업을 확대한다.
- **3. CPU 이용률 저하**: I/O 대기로 유효 실행 감소한다.
- **4. 다중프로그래밍 증가**: CPU 유휴를 작업 부족으로 오판이다.
- **5. 프로세스별 프레임 감소**: 워킹 셋 부족과 폴트 악화이다.

#### 한줄 요약

- 폴트•I/O•CPU 유휴의 **양의 피드백** 차단이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **요구 페이징(Demand Paging)**: 실제 참조로 페이지 폴트가 발생한 시점에만 페이지를 메모리에 적재하는 방식이다.
- **스레싱 전이(Thrashing Transition)**: 메모리 수요가 가용 프레임을 넘어 정상 요구 페이징이 반복 교체로 바뀌는 지점이다.

</details>

| 가상 메모리 상태 | 관측 징후 | 운영 의미 |
|:---|:---|:---|
| **정상 요구 페이징** | 워킹 셋 수용•**간헐적 폴트** | 폴트 처리 뒤 유효 실행이 계속 증가 |
| **스레싱** | 워킹 셋 미수용•**반복 교체** | 교체 입출력이 유효 실행을 압도해 처리량 하락 |
| **스레싱 전이** | 프레임 수요가 가용량을 넘는 경계 | 작업 수 축소•프레임 재배분 판단 시점 |

> 요약: **워킹 셋 미수용•반복 폴트**가 겹치면 **스레싱**을 판정한다.

#### 한줄 요약

- **워킹 셋 수용•재참조 폴트**로 정상•스레싱을 구분한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **주요 페이지 폴트(Major Page Fault)**: 저장장치 읽기가 필요한 페이지 폴트이다.
- **경미 페이지 폴트(Minor Page Fault)**: 메모리 주소 매핑만 복구하는 페이지 폴트이다.
- **수용 제어(Admission Control)**: 메모리 여유를 검사해 새 작업의 실행 허용 여부를 결정하는 절차이다.
- **재참조량(Refault Count)**: 최근 퇴출한 페이지를 다시 요구한 횟수이다.
- **교체량(Page Swap Volume)**: 메모리와 저장장치 사이에서 바꾼 페이지 양이다.
- **교환 I/O(Swap I/O)**: 메모리 압박 때 페이지를 보조 저장장치로 내보내거나 다시 읽는 입출력이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 파일 최초 접근 폴트와 재참조 **스레싱 혼동** | 주요•경미 폴트와 **재참조•교체량 분리 계측** | 정확한 **스레싱 판정** |
| 전체 평균이 특정 프로세스의 **워킹 셋 부족 은폐** | 프로세스•컨테이너별 **폴트율•상주 집합 감시** | **메모리 병목 주체** 식별 |
| 메모리 압박 중 작업을 추가해 **프레임 부족 악화** | **수용 제어•동시 작업 축소**와 최소 워킹 셋 보장 | **처리량 붕괴** 방지 |
| 교환 I/O가 저장장치의 **정상 요청 지연** | 교환 한도•우선순위와 **메모리 증설•작업 중단** | 연쇄 **I/O 지연** 완화 |

#### 한줄 요약

- 폴트율 상한 초과 시 **수용 제어•프레임 재배분**이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **폴트율 상한**: 스레싱 판정을 위한 페이지 폴트 빈도 기준이다.
- **워킹 셋 수용**: 작업 수와 프레임 재배분을 정하는 용량 기준이다.

</details>

- **폴트율 상한**을 넘고 워킹 셋이 미수용되면 **작업 수 축소•프레임 재배분**이 핵심이다.

#### 한줄 요약

- 폴트율 초과•워킹 셋 미수용 시 **작업 수 축소**가 핵심이다.
