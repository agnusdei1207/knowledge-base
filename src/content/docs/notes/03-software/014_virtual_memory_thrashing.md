## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **워킹 셋(Working Set)**: 프로세스가 일정 시간 창($\Delta$) 동안 빈번하게 참조하여 물리 메모리에 반드시 상주해야 하는 핵심 페이지 집합.
- **메이저 페이지 폴트(Major Page Fault)**: 가상 메모리 페이지가 물리 DRAM에 없어 저속 디스크 스왑 영역에서 블록을 읽어와야 하는 고비용 I/O 인터럽트.

</details>

- 정의/개념: 가용 물리 메모리가 프로세스들의 **워킹 셋(Working Set)** 에 미치지 못해 스왑 I/O가 폭증하고 CPU 이용률이 급락하는 시스템 성능 붕괴 현상
- 배경/필요성: 다중프로그래밍 정도(DOM)의 과도한 증가에 따른 연속적 메이저 페이지 폴트(Page Fault) 방지 및 시스템 처리량 보장 필요

#### 한줄 요약

- 물리 메모리 부족으로 Swap I/O가 폭증하여 CPU 이용률이 급락하는 스레싱을 워킹 셋·PFF 기반으로 방지

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다중프로그래밍 정도(Degree of Multiprogramming, DOM)**: 동시에 물리 메모리에 적재되어 실행 중인 프로세스 수.
- **페이지 폴트 빈도(Page Fault Frequency, PFF)**: 단위 시간당 페이지 폴트 발생 횟수를 기준으로 프레임 할당량을 동적으로 조정하는 기법.

</details>

- **DOM** 임계점 초과 시 CPU 이용률·처리량이 급감하는 스레싱 발생
- 빈번한 **메이저 페이지 폴트** 기반 디스크 I/O 대기 급증 및 CPU 유휴 상태 심화
- **워킹 셋** 보장 또는 **PFF** 기반 동적 프레임 할당으로 스레싱 방지

#### 한줄 요약

- DOM이 임계점을 초과하면 페이지 폴트가 폭증하고 CPU가 유휴 상태에 빠지는 스레싱이 발생

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워킹 셋 윈도우(Working Set Window, Δ)**: 워킹 셋을 계산하기 위해 최근 참조 이력을 추적하는 시간 창으로, Δ가 클수록 더 많은 페이지를 워킹 셋으로 포함.
- **상주 집합(Resident Set)**: 프로세스의 가상 페이지 중 현재 물리 메모리에 실제로 적재된 페이지 집합.

</details>

```text
[ 스레싱 방어 구조 ]
상주 집합 관리자 (물리 프레임 할당 통제)
├─ 워킹 셋 추적기 (워킹 셋 윈도우 Δ 내 참조 페이지 집합 계산)
├─ 페이지 폴트 감시기 (PFF 측정·상하한 기준 비교)
└─ 부하 제어기
    ├─ PFF 초과 시: 프레임 추가 할당
    ├─ PFF 미달 시: 프레임 회수
    └─ 스레싱 탐지 시: DOM 축소 (프로세스 일시 중단)
```

선의 의미: 가지(`├─`, `└─`)는 스레싱 방어 구성 요소 간 소유 관계 및 제어 흐름

| 구성요소 | 책임 |
|:---|:---|
| 워킹 셋 추적기 | 윈도우 Δ 내 **워킹 셋** 계산으로 필수 프레임 요구량 산출 |
| 상주 집합 관리자 | **워킹 셋** 크기에 따른 물리 프레임 할당·회수 관리 |
| 페이지 폴트 감시기 | 단위 시간당 **PFF** 측정 및 상하한 임계값 비교 |
| 부하 제어기 | 스레싱 탐지 시 **DOM 축소** 기반 물리 메모리 여유 확보 |

#### 한줄 요약

- 워킹 셋 추적기가 필수 프레임을 계산하고 PFF 감시기가 스레싱을 탐지하면 부하 제어기가 DOM을 축소

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스레싱 연쇄 악순환(Thrashing Cascade)**: 메모리 부족 → 페이지 폴트 폭증 → CPU 유휴 → OS DOM 증가 → 메모리 추가 부족의 순환 악화 패턴.

</details>

```text
DOM 증가 (프로세스 다수 적재)
   │
   ▼
1. 프로세스당 프레임 할당량 < 워킹 셋 크기
   │
   ▼
2. 메이저 페이지 폴트 폭증 → Swap I/O 급증
   │
   ▼
3. 프로세스 대부분 I/O 대기 → CPU 이용률 급락
   │
   ├─ 스레싱 탐지 시: DOM 축소 → 물리 메모리 확보 → 정상화
   └─ OS 오판 시: CPU 유휴 → DOM 추가 증가 → 악순환 심화
```

**동작 원리** 1. **프레임 부족 발생**: DOM 증가로 프로세스당 할당 프레임이 **워킹 셋** 요구량 미달
2. **페이지 폴트 폭증**: 필수 페이지가 물리 메모리에 없어 **메이저 페이지 폴트** 연속 발생
3. **CPU 유휴 상태**: 대부분 프로세스가 Swap I/O 대기로 CPU 이용률 급락
4. **스레싱 방지**: 워킹 셋 기반 프레임 보장 또는 **PFF** 상한 초과 시 **DOM 축소** 기반 물리 메모리 확보

#### 한줄 요약

- 프레임 부족 → 폴트 폭증 → CPU 유휴의 스레싱 악순환을 DOM 축소와 PFF 기반 프레임 조정으로 차단

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로세스 시작 시 전체 페이지를 적재하지 않고 참조 시점에 디스크에서 페이지를 적재하는 가상 메모리 기본 기법.

</details>

| 구분 | 정상 요구 페이징 | 스레싱 상태 |
|:---|:---|:---|
| 페이지 폴트 발생률 | 초기 적재 후 안정화 | **메이저 페이지 폴트** 지속 폭증 |
| CPU 이용률 | 높음 (연산 중심) | 매우 낮음 (I/O 대기 중심) |
| 주요 시간 소비 | CPU 명령어 실행 | **Swap I/O** 대기 |
| 해결책 | LRU 등 페이지 교체 알고리즘 적용 | **DOM 축소**·워킹 셋 프레임 보장 |

#### 한줄 요약

- 정상 상태는 CPU 연산 중심이고, 스레싱은 Swap I/O 대기로 CPU가 유휴 상태에 빠짐

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **cgroups 메모리 한도(cgroups Memory Limit)**: 리눅스 컨트롤 그룹으로 컨테이너·프로세스 그룹의 최대 물리 메모리 사용량을 제한하여 메모리 독점 방지.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DOM 과다로 전체 시스템 **스레싱** 발생 | **워킹 셋** 기반 최소 프레임 보장·**DOM 축소** 적용 | Swap I/O 감소 및 CPU 이용률 회복 |
| 특정 프로세스 프레임 과부족으로 **PFF** 불균형 | **PFF** 상하한 기준 동적 프레임 재배분 | 프레임 할당 균형 확보 |
| 컨테이너 메모리 독점으로 노드 전체 스레싱 유발 | **cgroups 메모리 한도**·OOM Killer 설정 | 단일 컨테이너 메모리 독점 차단 |

#### 한줄 요약

- 스레싱은 DOM 축소와 워킹 셋 보장으로, PFF 불균형은 동적 재배분으로, 컨테이너 독점은 cgroups 한도로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스레싱 방지 선택 기준**: PFF·워킹 셋 기반 프레임 보장과 DOM 축소 중 우선 적용 방법을 물리 메모리 용량과 워크로드 특성에 따라 결정하는 기준.

</details>

- 운영체제 레벨은 **PFF/워킹 셋** 기반 프레임 보장, 컨테이너 환경은 **cgroups 메모리 한도** 격리 적용

#### 한줄 요약

- 전통 OS 환경은 PFF·워킹 셋으로 프레임을 보장하고, 컨테이너 환경은 cgroups 한도로 메모리를 격리
