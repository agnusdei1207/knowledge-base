## 미리 알고가기

- **DB(Database)**: ‘디비’로 읽고 영문 머리글자를 딴 약어이며, 데이터를 구조화해 저장·관리하는 시스템임
- **NoSQL(Not Only SQL)**: ‘노에스큐엘’로 읽고 영문 핵심 글자를 조합한 표기이며, 관계형 표 이외의 데이터 모델을 지원함
- **JSON(JavaScript Object Notation)**: ‘제이슨’으로 읽고 영문 머리글자를 딴 약어이며, 키와 값으로 문서 데이터를 표현함
- **BSON(Binary JSON)**: ‘비슨’으로 읽고 Binary와 JSON을 결합한 이름이며, 자료형을 포함한 이진 문서를 저장함
- **레플리카셋 (Replica Set)**: 사본 복제와 주 복제본 선출을 수행함
- **샤딩 (Sharding)**: 샤드 키로 데이터를 분산함
- **쓰기 확인 수준 (Write Concern)**: 완료에 필요한 복제본 확인 수를 정함
- **95백분위 지연 (95th Percentile Latency, p95)**: 요청 95%가 완료되는 지연 기준임
- **컬렉션(Collection)**: 비슷한 용도의 BSON 문서를 모아 관리하는 논리 단위임
- **문서(Document)**: 필드와 값의 쌍을 중첩 객체·배열로 표현하는 저장 단위임
- **내장(Embedding)**: 함께 조회·변경하는 하위 데이터를 한 문서 안에 포함하는 모델링 방식임
- **보조 인덱스(Secondary Index)**: 기본 식별자 외의 필드로 문서를 빠르게 찾게 하는 인덱스임
- **집계 파이프라인(Aggregation Pipeline)**: 문서를 단계별로 필터·변환·그룹화하는 처리 흐름임
- **주 복제본(Primary Replica)**: 레플리카셋에서 쓰기를 받아 변경 순서를 확정하는 구성원임
- **보조 복제본(Secondary Replica)**: 주 복제본의 변경 로그를 적용해 사본을 유지하는 구성원임

## Ⅰ. 개요

- 정의/개념: **BSON 문서 단위**로 저장·조회하는 데이터베이스
- 기존 한계: 관계형 분해로 **중첩 객체 조인·변경 비용** 증가

### 쉽게 이해하기 (학습용)
- 상품 목록과 배송지를 함께 넣어 한 문서 단위로 읽고 고치는 저장소임

## Ⅱ. 특징

- **중첩 객체·배열**을 단일 문서로 저장
- **문서 단위 원자성**과 유연한 필드 구조 제공
- 내장은 조인을 줄이나 **중복·문서 크기** 증가

### 쉽게 이해하기 (학습용)
- 함께 쓰는 정보는 편하나 경계를 잘못 잡으면 중복 갱신이 생김

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 컬렉션·문서 | 문서를 원자 저장 단위로 묶음 |
| 인덱스 | 필드 검색과 정렬 경로를 제공함 |
| 레플리카셋 | 변경 복제와 주 복제본 선출을 수행함 |
| 샤딩 계층 | 샤드 키 범위와 요청 경로를 관리함 |

```text
  앱라우팅
      ↓
  샤드선택
      ↓
  주본기록
      ↓
  사본동기
```

> 요약: 라우터가 샤드 키로 문서의 복제본에 요청을 전달함

### 쉽게 이해하기 (학습용)
- 문서와 인덱스 및 레플리카셋과 샤딩 계층이 요청을 처리함

## Ⅳ. 원리 및 절차 흐름도

```text
  요청수신
      ↓
  샤드선택
      ↓
  주본기록
      ↓
  로그복제
      ↓
  결과응답
```

| 절차 | 설명 |
|:---|:---|
| 요청수신 | 문서와 키 및 쓰기 확인 수준을 수신함 |
| 샤드선택 | 샤드 키 범위로 대상 샤드를 정함 |
| 주본기록 | 주 복제본에 변경과 복제 로그를 기록함 |
| 로그복제 | 보조 복제본이 변경 로그를 적용함 |
| 결과응답 | 확인 수준 충족 시 성공을 반환함 |

> 요약: 샤드 선택 뒤 복제본 확인 수를 충족하면 완료함

### 쉽게 이해하기 (학습용)
- 샤드 키로 주 복제본을 찾고 변경을 사본에 전파함

## Ⅴ. 종류 및 비교

| 데이터 모델 | MongoDB | 관계형 데이터베이스 |
|:---|:---|:---|
| 적용 기준 | 중첩 객체·**가변 필드** | 강한 제약·**관계 조인** |
| 핵심 특징 | BSON 문서·**내장 구조** | 정형 행·**참조 무결성** |
| 한계 | 중복·문서 크기·**샤드 편중** | 스키마 변경·**수평 분산 복잡도** |

> 요약: 관계형은 조인, MongoDB는 문서·샤딩

### 쉽게 이해하기 (학습용)
- 관계형 DB는 표를 연결하고 MongoDB는 문서에 함께 묶음

## Ⅵ. 실무 사례

1. 상품 속성을 **단일 문서에 내장**
2. 주문 문서를 **샤드 키로 분산**

### 쉽게 이해하기 (학습용)
- 상품 속성을 한 문서에 내장하면 한 번에 읽기 쉽지만 중복 필드의 갱신 비용과 문서 크기를 함께 확인해야 함
- 샤드 키를 적용한 뒤 샤드별 요청 점유율을 측정하면 특정 키 범위에 부하가 몰리는지를 판단할 수 있음

## Ⅶ. 결론

- 중첩 조회는 **내장**, 분산은 **샤드 키**

### 쉽게 이해하기 (학습용)
- MongoDB는 관련 데이터를 한 문서에서 처리할 때 강점이 있으며 문서 경계와 분산 키가 실제 접근 패턴에 맞아야 함
