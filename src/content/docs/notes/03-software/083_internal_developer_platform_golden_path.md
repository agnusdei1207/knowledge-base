## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **골든 패스(Golden Path)**: 검증된 도구•템플릿•기본값을 조합해 공통 개발•배포 작업을 빠르고 안전하게 수행하도록 지원하는 권장 경로이다.
- **환경 편차(Environment Drift)**: 팀별 선택으로 구성이 달라진 상태이다.
- **학습 비용(Learning Cost)**: 팀별 도구와 절차에 적응하는 부담이다.
- **보안 누락(Security Omission)**: 팀별 구성에서 필수 통제가 빠진 상태이다.

</details>

- 정의/개념: **골든 패스**는 검증된 도구•템플릿•기본값으로 공통 작업을 빠르고 안전하게 수행하도록 지원하는 권장 경로이다.
- 배경/필요성: 팀별 도구•구성 선택은 **환경 편차**, **학습 비용**, **보안 누락**을 일으킨다.

#### 한줄 요약

- 검증된 기본값과 승인 예외를 결합한 **골든 패스**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **검증 템플릿(Validated Template)**: 표준 경로를 시작하도록 조직이 제공하는 골격이다.
- **기본값(Default)**: 안전한 시작을 위해 미리 정한 설정이다.
- **우회 허용(Approved Bypass)**: 정당한 예외에 표준 경로 밖의 수행을 승인하는 방식이다.
- **중앙 템플릿 갱신**: 공통 도구 버전과 보안 패치를 권장 경로 사용자에게 전파하는 활동이다.

</details>

- **검증 템플릿**과 **기본값**으로 표준 경로의 사용 비용을 줄인다.
- 확장 지점과 **우회 허용**으로 팀별 예외 요구를 수용한다.
- **중앙 템플릿 갱신**으로 도구 버전•보안 패치 전파가 핵심이다.

#### 한줄 요약

- 낮은 사용 비용과 **중앙 템플릿 갱신**이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **시작 템플릿(Starter Template)**: 표준 구조•의존성•기본값을 담은 서비스 시작 골격이다.
- **권장 워크플로(Recommended Workflow)**: 빌드•검증•배포를 검증된 순서로 실행하는 기본 흐름이다.
- **확장 지점(Extension Point)**: 표준 흐름을 깨지 않고 팀별 설정•플러그인을 연결하는 접점이다.
- **탈출구(Escape Hatch)**: 정당한 예외를 승인된 방식으로 우회하는 경로이다.
- **경로 분석(Path Analytics)**: 단계별 시간과 실패 및 우회 지점을 측정해 골든 패스의 마찰을 찾는 활동이다.

</details>

```text
                        [시작 템플릿]
                              |
                              |
[확장 지점] -------- [권장 워크플로] -------- [탈출구]
                              |
                              |
                         [경로 분석]
```

선의 의미: 시작 템플릿과 권장 워크플로의 선은 표준 구조•의존성•기본값 제공 관계, 확장 지점과 탈출구의 선은 권장 워크플로에 연결되는 지원 확장과 승인 예외 관계, 권장 워크플로와 경로 분석의 선은 사용 시간•실패•우회 구간의 측정 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 시작 템플릿 | 표준 구조•의존성•기본값 제공 |
| 권장 워크플로 | 빌드•검증•배포 기본 경로 정의 |
| 확장 지점 | 지원되는 팀별 설정•플러그인 연결 |
| 탈출구 | 정당한 예외의 승인 우회 경로 제공 |
| 경로 분석 | 단계 시간•실패•우회 구간 측정 |

#### 한줄 요약

- **시작 템플릿**, **권장 워크플로**, **확장 지점**, **탈출구**, **경로 분석**의 연결 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **가드레일(Guardrail)**: 골든 패스에서 정책을 자동 집행하는 통제이다.
- **승인 확장(Approved Extension)**: 조직이 지원하기로 한 팀별 확장이다.
- **만료 조건(Expiration Condition)**: 일시 예외를 종료하는 기준이다.
- **단계 시간(Stage Time)**: 골든 패스 각 단계에 걸린 시간이다.
- **실패 지표(Failure Metric)**: 권장 경로의 단계별 실패를 측정한 값이다.
- **우회 지표(Bypass Metric)**: 사용자가 표준 경로를 벗어난 비율이다.
- **시작 템플릿•가드레일 적용**: 서비스 유형에 맞는 구조•기본값•정책 통제를 구성하는 동작이다.
- **권장 워크플로 실행**: 표준 빌드•검증•배포 경로를 자동 수행하는 동작이다.
- **미충족 요구•우회 사유 판정**: 표준 경로가 팀 요구를 지원하는지와 예외 필요성을 확인하는 동작이다.
- **승인 확장•탈출구 통제**: 지원 확장 또는 만료 조건이 있는 일시 우회를 제공하는 동작이다.
- **경로 지표•마찰 개선**: 단계 시간•실패•우회•만족도를 분석해 기본 경로를 고치는 동작이다.

</details>

```text
[서비스 유형•팀 요구]
        |
        v
+---------------------------------+
| 1. 시작 템플릿•가드레일 적용  |
+---------------------------------+
        |
        v
+---------------------------------+
| 2. 권장 워크플로 실행          |
+---------------------------------+
        |
        v
+---------------------------------+
| 3. 미충족 요구•우회 사유 판정 |
+---------------------------------+
        |
   +----+----+
   | 충족    | 미충족
   |         v
   |  +---------------------------------+
   |  | 4. 승인 확장•탈출구 통제       |
   |  +---------------------------------+
   |         |
   +----+----+
        |
        v
+---------------------------------+
| 5. 경로 지표•마찰 개선        |
+---------------------------------+
        |
        v
[템플릿•기본값•확장 지점 갱신]
```

### 동작 원리

1. **시작 템플릿•가드레일 적용**: **가드레일**을 포함한 표준 시작점을 구성한다.
2. **권장 워크플로 실행**: 빌드•검증•배포 자동을 수행한다.
3. **미충족 요구•우회 사유 판정**: 예외 필요성을 확인한다.
4. **승인 확장•탈출구 통제**: **승인 확장**, **탈출구**, **만료 조건**으로 예외를 통제한다.
5. **경로 지표•마찰 개선**: **단계 시간**, **실패 지표**, **우회 지표**로 기본 경로를 갱신한다.

> 요약: 유용한 기본 경로와 안전한 확장•탈출구를 제공하고 실제 마찰 데이터로 개선한다.

#### 한줄 요약

- **권장 워크플로 실행**과 **경로 지표•마찰 개선**의 순환이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **골든 패스 중심**: 조직 표준과 자동 기본값을 우선 제공하고 예외만 확장하는 플랫폼 방식이다.
- **자유 선택형**: 팀이 도구와 구성을 직접 선택해 자율 실험을 우선하는 방식이다.

</details>

| 플랫폼 사용 경로 | 골든 패스 중심 | 자유 선택형 |
|:---|:---|:---|
| 적용 기준 | 반복 경로와 조직 표준 우선 | 자율 실험과 비정형 구성 우선 |
| 핵심 특징 | 검증 템플릿과 자동 기본값 | 팀별 도구•구성 직접 선택 |
| 한계 | 경직된 경로와 예외 요구 제한 | 구성 편차와 중복 운영 |

> 요약: 기본 경로와 확장 지점으로 표준과 자율성을 조율하는 것이 핵심이다.

#### 한줄 요약

- 반복 표준은 **골든 패스 중심**, 자율 실험은 **자유 선택형**이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **지원 버전(Supported Version)**: 조직이 유지보수하는 도구와 의존성 버전이다.
- **지원 기간(Support Period)**: 조직이 해당 버전을 지원하는 기간이다.
- **자동 갱신(Automatic Update)**: 새 표준 버전을 사용자 경로에 전파하는 정책이다.
- **운영 구조(Operational Structure)**: 추상화 아래의 실제 구성요소와 관계이다.
- **운영 책임(Operational Ownership)**: 장애 진단과 복구를 맡은 주체이다.
- **운영 로그(Operational Log)**: 추상화 아래의 장애 사건 기록이다.
- **복구 절차(Recovery Procedure)**: 장애를 정상 상태로 되돌리는 순서이다.
- **실패율(Failure Rate)**: 권장 경로 실행 중 실패한 비율이다.
- **만족도(Satisfaction)**: 개발자가 골든 패스를 유용하다고 평가한 정도이다.
- **가치 스트림(Value Stream)**: 요청부터 가치 전달까지 이어지는 활동 흐름이다.
- **기술별 최소 경로(Minimum Technical Path)**: 기술 유형별로 유지할 최소 표준 경로이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 표준 경로를 강제해 팀별 정당한 예외가 비공식화 | **확장 지점**, **탈출구**, **우회 허용** 제공 | 비공식 우회 감소 |
| 기본 도구•의존성 버전이 낡아 보안과 호환성 저하 | **지원 버전**, **지원 기간**, **자동 갱신** 운영 | 의존성•정책 현행화 |
| 하부 구조를 숨겨 장애 원인과 복구 책임이 불명 | **운영 구조**, **운영 책임**, **운영 로그**, **복구 절차** 공개 | 장애 진단 시간 단축 |
| 우회율만 낮춰 강제 사용을 자발적 채택으로 오판 | **단계 시간**, **실패율**, **만족도**와 함께 해석 | 강제 사용•자발 채택 구분 |
| 유사 경로가 늘어 선택 부담과 유지 비용 증가 | **가치 스트림**과 **기술별 최소 경로** 통합 | 선택•유지 비용 감소 |

> 적용 사례: 서비스 템플릿의 구축시간•실패율•우회율을 측정해 마찰 지점을 개선

#### 한줄 요약

- **단계 시간**, **실패율**, **만족도**에 기반한 경로 마찰 개선이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **플랫폼 경로 선택 기준**: 업무의 반복성•표준화 가능성과 팀 자율성 요구를 평가해 골든 패스와 예외 경로의 적용 범위를 정하는 기준이다.

</details>

- **플랫폼 경로 선택 기준**에 따라 반복 경로는 **골든 패스**, 지원 확장은 **확장 지점**, 일시 예외는 **탈출구**를 적용한다.

#### 한줄 요약

- 표준성과 자율성에 맞는 **플랫폼 경로 선택 기준**이 핵심이다.
