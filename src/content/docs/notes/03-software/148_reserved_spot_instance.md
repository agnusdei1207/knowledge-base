## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **예약 인스턴스(RI / Savings Plans)**: 1년 또는 3년 장기 약정을 맺고 기본 요율 대비 최대 72% 할인된 가격으로 컴퓨팅 용량을 확보하는 요율 최적화 옵션.
- **스팟 인스턴스(Spot Instance)**: CSP의 미사용 잉여 컴퓨팅 자원을 최대 90% 할인된 가격에 입찰 사용하되, CSP 자원 부족 시 2분 전 경고 후 회수되는 초저비용 옵션.

</details>

- 정의/개념: 클라우드 인프라 비용을 최적화하기 위해 **장기 약정 기반의 예약 인스턴스(RI/SP)와 잉여 자원 기반의 스팟 인스턴스(Spot)를 조합**하는 구매 전략
- 배경/필요성: 모든 인프라를 기본 정가(On-Demand)로 운영 시 발생하는 **컴퓨팅 비용 과다 청구 및 워크로드별 중단 허용도 차이 미반영 위험** 직면

#### 한줄 요약

- 베이스라인 워크로드는 예약 약정으로 단가를 낮추고 중단 가능한 배치/무상태 워크로드는 스팟으로 최대 90% 비용을 절감

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **2분 회수 경고(2-Minute Interruption Notice)**: 스팟 인스턴스 회수 시 CSP가 EventBridge를 통해 2분 전에 사전 노티를 발송하여 작업 정리 유예를 제공.
- **스팟 플릿(Spot Fleet)**: 단일 인스턴스 회수 위험을 분산하기 위해 다수의 인스턴스 타입(c5, m5, r5)을 묶어 최적의 가용성을 유지하는 풀(Pool).

</details>

- 24/365 가동되는 안정적 베이스라인 트래픽을 위한 **Savings Plans / RI 약정 할인**
- 언제든 재시작 가능한 무상태(Stateless) 웹/배치를 위한 **최대 90% 초저가 스팟 인스턴스**
- 예측 불가능한 돌발 스파이크 트래픽을 즉시 흡수하는 **정가 온디맨드(On-Demand) 병용**

#### 한줄 요약

- 워크로드의 지속성과 중단 허용도를 분석하여 예약, 스팟, 온디맨드를 최적 비율로 혼합 운영

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **혼합 인스턴스 오토스케일링 그룹(Mixed Instances ASG)**: 단일 클러스터 내에서 On-Demand/RI와 Spot 인스턴스를 특정 비율(예: 20:80)로 혼합 프로비저닝하는 아키텍처.

</details>

```text
[ 클라우드 컴퓨팅 혼합 인스턴스 구매 최적화 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      혼합 인스턴스 그룹 (Mixed Instances Group)        │
 ├─────────────────────┬───────────────────┬──────────────────────────────┤
 │ 1. 베이스라인 용량  │ 2. 무상태 확장    │ 3. 피크 타임 돌발 확장      │
 ├─────────────────────┼───────────────────┼──────────────────────────────┤
 │ • Compute Savings   │ • Spot Fleet 풀   │ • On-Demand 인스턴스         │
 │   Plans (최대 66%↓) │   - 최대 90% 할인 │   - 정가 무약정 결제         │
 │ • 24/365 고정 트래픽│   - EKS Worker 노드│   - 스팟 매진 시 자동 폴백   │
 │ • Stateful Core DB  │   - AI/배치 워커  │   - 0% 중단 위험 보장        │
 └─────────────────────┴───────────────────┴──────────────────────────────┘
```

선의 의미: 기본 수요는 Savings Plans, 무상태 확장은 Spot, 긴급 폴백은 On-Demand로 분기 결합하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 예약 약정 (RI / SP) | 코어 DB 및 항시 가동 서버에 대해 **1~3년 약정 요율을 적용하여 고정 비용 절감** |
| 스팟 플릿 (Spot Fleet) | 이종 인스턴스 풀(Pool)을 구성하여 **무상태 웹/배치 작업을 90% 할인된 가격에 처리** |
| 온디맨드 (On-Demand) | 예측 불가한 트래픽 스파이크 및 **스팟 자원 회수 시 즉시 가동되는 안전 버퍼** |
| 스팟 핸들러 (Handler) | 2분 회수 경보 수신 시 **K8s Pod Cordon/Drain을 실행하여 무중단 태스크 이체** |

#### 한줄 요약

- 예약 약정(기본 부하), 스팟 플릿(무상태 확장), 온디맨드(비상 버퍼), 스팟 핸들러로 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스팟 인스턴스 2분 회수 대응 절차**: 회수 이벤트 수신 $\to$ Cordon 할당 차단 $\to$ Drain 태스크 이체 $\to$ 대체 스팟/온디맨드 확보 $\to$ 무중단 재개.

</details>

```text
[ 스팟 인스턴스 2분 회수 자동 복구 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. CSP 2분 전 회수 이벤트(Notice) 수신 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. K8s Cordon: 대상 노드 신규 배포 차단│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. K8s Drain: 실행 중 Pod 타 노드 이체│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. Auto-Scaling: 대체 Spot/On-Demand 기동
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 트래픽 무중단 정상 서비스 지속     │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 이벤트 수신: EventBridge가 `aws.ec2.spot-instance-interrupt-notice` 신호를 감지하여 컨트롤러에 전달.
2. 할당 차단: K8s Spot Handler가 해당 노드에 `kubectl cordon`을 내려 신규 파드 배치를 즉시 금지.
3. 태스크 이체: `kubectl drain`을 실행하여 실행 중인 파드를 다른 정상 노드로 부드럽게 퇴거(Graceful Shutdown).
4. 대체 자원 확보: ASG가 Spot Fleet 풀에서 다른 인스턴스 타입을 즉시 프로비저닝하거나 온디맨드로 보충.
5. 무중단 재개: 클라이언트는 500 에러 없이 정상적으로 서비스를 지속 이용.

#### 한줄 요약

- 이벤트 수신 $\to$ Cordon 차단 $\to$ Drain 이체 $\to$ 대체 노드 기동 $\to$ 정상 지속의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **온디맨드 vs 예약(SP) vs 스팟**: 가격 할인율, 중단 위험, 적합 워크로드에 따른 3대 인스턴스 비교.

</details>

| 구분 | 온디맨드 (On-Demand) | 예약 인스턴스 (Savings Plans) | 스팟 인스턴스 (Spot Instance) |
|:---|:---|:---|:---|
| **적용 기준** | 단기 프로젝트, 신규 서비스 출시, 예측 불가 트래픽 | 24/365 항시 가동 코어 DB, 베이스라인 웹/API | 대규모 배치 연산, AI 모델 학습, CI/CD 러너 |
| **핵심 특징** | **약정 0%, 중단 위험 0%, 정가 종량제 과금** | **1~3년 약정, 최대 66~72% 할인, 무중단 안정성** | **최대 90% 초저가 할인, 2분 전 회수 위험 수용** |
| **한계** | 대규모 장기 운영 시 인프라 비용 극대화 | 약정 기간 내 다운사이징/취소 불가 리스크 | 회수 시 상태 유실 위험 (Stateful DB 절대 적용 금지) |

#### 한줄 요약

- 정가는 온디맨드, 베이스라인은 Savings Plans 약정, 중단 가능한 배치는 스팟을 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **용량 최적화 할당 전략(Capacity-Optimized Strategy)**: 스팟 인스턴스 요청 시 가장 회수 확률이 낮은 인스턴스 풀을 자동으로 골라 프로비저닝하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특정 인스턴스 타입 스팟 잔여 자원 고갈로 증설 실패 | **Spot Fleet에 `capacity-optimized` 할당 전략 및 10개 이상 타입 지정** | 스팟 프로비저닝 성공률 99.9% 달성 |
| 스팟 인스턴스 회수로 인한 데이터베이스 상태(State) 유실 | **Stateful DB는 전면 배제하고 오직 무상태(Stateless) 파드에만 스팟 적용** | 데이터 정합성 파괴 원천 차단 |
| 장기 배치 연산 도중 스팟 회수로 작업 처음부터 재실행 | **애플리케이션 체크포인팅(Checkpointing) 구현 및 중간 상태 S3 저장** | 회수 시 마지막 체크포인트부터 즉시 재개 |

#### 한줄 요약

- 이종 타입 풀 구성, 무상태 한정 적용, 체크포인팅을 통해 스팟 인스턴스의 위험을 완벽히 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스마트 인스턴스 믹스(Smart Instance Mix)**: 전체 워크로드의 50%는 Savings Plans, 40%는 Spot, 10%는 On-Demand로 최적 배분하는 엔터프라이즈 비용 최적화 표준.

</details>

- **예약 및 스팟 인스턴스** 기반 클라우드 FinOps의 핵심 비용 절감 무기이며, 워크로드의 상태 유무와 트래픽 패턴을 엄밀히 분류하여 스마트 인스턴스 믹스를 구성해야 함

#### 한줄 요약

- 베이스라인의 예약 약정과 무상태 확장의 스팟 인스턴스를 결합하여 최대의 비용 효율성을 달성
