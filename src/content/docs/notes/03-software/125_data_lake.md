## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 레이크(Data Lake)**: 정형, 반정형(JSON, 로그), 비정형(이미지, 음성) 데이터를 원시 형태(Raw) 그대로 저비용 객체 스토리지(S3, GCS)에 저장하는 분석 저장소.
- **Schema-on-Read**: 적재 시점에 엄격한 테이블 스키마를 강제하지 않고, 분석가가 쿼리를 실행하는 읽기 시점에 스키마를 동적으로 부여하는 방식.

</details>

- 정의/개념: 정형·비정형 데이터를 원시 포맷 그대로 객체 스토리지에 저장하고 **Schema-on-Read 기반으로 분석 및 AI/ML 학습을 지원**하는 대규모 데이터 집적소
- 배경/필요성: 전통적 DW의 Schema-on-Write 방식 경직성으로 인한 **비정형 데이터 수용 불가 및 사전 정제(ETL) 비용 급증 한계**

#### 한줄 요약
- Schema-on-Read는 적재 시점의 비용을 없애는 대신 해석 비용을 모든 조회로 분산시키므로, 카탈로그와 정제 계층이 없으면 쌓아 둔 데이터를 찾지 못하는 늪으로 굳는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Data Swamp(데이터 늪)**: 메타데이터 관리와 거버넌스 부재로 인해 필요한 데이터를 찾을 수 없고 쓸모없는 쓰레기 데이터만 쌓인 상태.
- **Medallion Architecture**: Bronze(원시 수집) $\to$ Silver(정제 및 필터링) $\to$ Gold(비즈니스 집계 마트) 3단계 데이터 정제 계층 구조.

</details>

- 정형, 반정형, 비정형 데이터를 원본 포맷 그대로 수용하는 **다형성 데이터 적재**
- 사전 스키마 없이 고속 적재 후 분석 시점에 해석하는 **Schema-on-Read 적용**
- 클라우드 객체 스토리지 기반의 **컴퓨팅과 스토리지 완전 분리(Decoupled)**

#### 한줄 요약
- 객체 스토리지와 Schema-on-Read를 통해 데이터 유실 없이 유연한 빅데이터 분석과 AI 학습을 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Bronze / Silver / Gold 계층**: 데이터 정제도에 따라 원시 데이터(Bronze), 정제된 파케이(Silver), 집계된 비즈니스 뷰(Gold)로 분류.

</details>

```text
[데이터 레이크 구성]
|-- 브론즈 계층
|-- 실버 계층
|-- 골드 계층
`-- 데이터 카탈로그
```

선의 의미: 계층 및 원천 데이터가 Bronze, Silver, Gold 영역으로 정제 승격되고 카탈로그로 통제되는 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 브론즈 계층 (Bronze) | 다양한 원천으로부터 수집된 원시(Raw) 데이터를 **가공 없이 시계열 스냅샷으로 영구 보존** | Append-Only 원본 보존 |
| 실버 계층 (Silver) | 중복 제거, 결측치 보정, 파티셔닝을 거쳐 **정제된 Parquet 포맷으로 변환 관리** | 스키마 일관성 확보 |
| 골드 계층 (Gold) | 비즈니스 도메인에 맞추어 고도화된 집계 테이블을 생성하여 **BI 및 AI 모델에 즉시 제공** | 도메인별 분석 마트 |
| 데이터 카탈로그 (Catalog) | 스키마, 저장 위치, 소유권, 데이터 계보(Lineage)를 관리하여 **데이터 늪(Data Swamp) 방지** | 검색성 및 거버넌스 제공 |

#### 한줄 요약
- 세 계층은 저장 위치의 구분이 아니라 정제 비용을 어디서 한 번만 치를지 나눈 경계이므로, 계층을 건너뛰고 원시 데이터를 직접 조회할수록 같은 정제를 질의마다 반복하게 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 레이크 처리 5단계**: 원본 S3 적재 $\to$ 카탈로그 크롤링 $\to$ Spark 실버 정제 $\to$ 골드 마트 생성 $\to$ Athena/Presto 쿼리 서빙.

</details>

```text
다양한 원천 시스템 데이터 스트림 유입
        │
   [원본 적재] IoT 로그, DB 변경분, 이미지를 S3 Bronze 버킷에 원본 그대로 적재
        │
   [카탈로그 등록] AWS Glue Crawler가 새로운 파일 파티션과 스키마 메타데이터 자동 등록
        │
   [실버 정제] Apache Spark 잡을 통해 이상치 제거, 스키마 검증, Parquet 압축 변환
        │
   [골드 집계] 비즈니스 KPI 및 분석 요건에 맞추어 일별/월별 집계 테이블 Gold 계층 생성
        │
   분석가가 Amazon Athena / Trino를 통해 Schema-on-Read 방식으로 대화형 SQL 질의
```

#### 한줄 요약
- 원본을 지우지 않기에 분석 로직이 바뀌어도 언제든 재처리할 수 있지만, 그 대가로 저장량과 작은 파일 수가 계속 늘어 조회 비용이 서서히 올라간다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DW vs Data Lake**: 고성능 정형 SQL 분석 전용 저장소인 DW와 무제한 다형성 원시 데이터 집적소인 Data Lake.

</details>

| 비교 항목 | 데이터 웨어하우스 (Data Warehouse) | 데이터 레이크 (Data Lake) |
|:---|:---|:---|
| 데이터 형태 | **고도로 정제된 2차원 정형 데이터** | **정형, 반정형(JSON), 비정형(이미지, 영상)** |
| 스키마 적용 시점 | **Schema-on-Write (적재 시점에 스키마 강제)** | **Schema-on-Read (읽기 쿼리 시점에 스키마 해석)** |
| 스토리지 비용 | 고비용 (고성능 SSD 및 블록 스토리지) | **초저비용 (클라우드 객체 스토리지 S3/GCS)** |
| 주 활용 목적 | **경영진 BI 리포트, 정형 OLAP 대시보드** | **AI/ML 모델 학습, 탐색적 빅데이터 분석** |

#### 한줄 요약
- 정형 지표 분석은 DW, 대규모 원시 보존과 AI 머신러닝 학습은 Data Lake를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Small File Problem**: 객체 스토리지에 KB 단위 자잘한 파일이 수백만 개 쌓여 메타데이터 조회(List API) 및 쿼리 병목을 유발하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거버넌스 부재로 검색이 불가능한 **Data Swamp** 전락 | **AWS Glue / Apache Atlas 데이터 카탈로그 및 태깅 의무화** | 데이터 검색성 및 계보 투명성 확보 |
| 수백만 개의 자잘한 Small File로 인한 S3 조회 지연 | **Spark 백그라운드 컴팩션(Compaction)으로 128MB~512MB 파일 병합**| 쿼리 스캔 성능 10배 가속 |
| S3 Key 파티셔닝 부재로 인한 전체 스토리지 풀스캔 | **S3 Key를 `year=YYYY/month=MM/day=DD` 파티션 구조로 설계** | 쿼리 비용 절감 및 Partition Pruning |
| 비정형 데이터 내 개인정보(PII) 유출 위험 | **데이터 수집 단계(Bronze)에서 Macie 기반 PII 마스킹 자동화** | 데이터 보안 및 컴플라이언스 준수 |

#### 한줄 요약
- 카탈로그 등록, Small File 컴팩션, 날짜 파티셔닝, PII 마스킹으로 데이터 늪화를 방지한다.

## Ⅶ. 결론

- 엔터프라이즈 빅데이터 수집, 생성형 AI/LLM 파인튜닝 데이터셋 구축 및 전사 데이터 레이크하우스(Lakehouse)의 **기초 원천 영속성 계층**으로 확립되었으며, 실무 구축 시에는 **데이터 늪(Data Swamp)화를 원천 차단하는 데이터 카탈로그(Glue/Atlas)와 메타데이터 거버넌스, 단계적 품질을 보장하는 메달리온 아키텍처(Bronze-Silver-Gold), 객체 스토리지 I/O 병목을 제거하는 Small File 컴팩션 및 시간 파티셔닝**을 결합하여 분석 생산성과 스토리지 비용 효율성을 극대화

#### 한줄 요약
- 데이터 레이크는 저비용 객체 스토리지와 Schema-on-Read를 바탕으로 모든 형태의 원천 데이터를 보존하고 AI 시대를 견인하는 핵심 인프라다.
