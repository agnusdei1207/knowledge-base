## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 레이크(Data Lake)**: 정형•반정형•비정형 원천을 원형에 가깝게 객체로 보존하고 소비 시점에 해석하는 저장소이다.

</details>

- 정의/개념: 다형식 원천을 원형에 가깝게 객체로 보존하는 **데이터 저장소**이다.
- 배경/필요성: 사전 스키마 적재는 다양한 원천의 **원본 보존•재해석** 제약이 발생한다.

#### 한줄 요약
- 문서•로그•사진을 원본 상자째 창고에 보관하고, 꺼내 쓸 때 목적에 맞는 구조로 해석한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **스키마 온 리드**: 데이터를 먼저 원형으로 저장하고 소비 시점에 구조와 자료형을 해석하는 방식이다.
- **다형식 수용**: 파일•로그•이미지 등 서로 다른 구조의 원천을 변환 전에 보존하는 특성이다.
- **데이터 신뢰 수준**: 원천•검증•정제 영역을 분리해 데이터가 허용되는 사용 범위를 나타내는 기준이다.

</details>

- 파일•로그•이미지를 원형에 가깝게 보존하는 **다형식 수용**이 핵심이다.
- 소비 시점에 구조를 해석하는 **스키마 온 리드**가 핵심이다.
- 원천•검증 영역을 분리한 **데이터 신뢰 수준**을 관리한다.

#### 한줄 요약
- 원천을 많이 모아도 위치•의미•품질•소유자를 찾을 카탈로그가 없으면 재사용할 수 없는 데이터 늪이 된다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **카탈로그**: 스키마•계보•소유자를 등록해 데이터 발견성을 제공하는 구성요소이다.
- **거버넌스**: 접근 정책과 관리 책임을 적용하는 통제 체계이다.
- **수집 계층**: 파일•로그•변경 데이터 등 여러 원천을 객체 스토리지로 전달하는 계층이다.
- **객체 스토리지**: 원천과 정제 데이터를 객체 키와 버전으로 보존하는 저장소이다.
- **데이터 영역**: 원천•검증•정제 데이터의 품질과 사용 범위를 나눈 논리 구역이다.
- **처리 엔진**: 객체 데이터를 검사•변환•분석하고 결과를 다시 저장하는 실행 계층이다.

</details>

```text
[데이터 레이크]
       |
       +-- [수집 계층]
       |
       +-- [객체 스토리지]
       |          |
       |          +-- [데이터 영역]
       |
       +-- [카탈로그•거버넌스]
       |
       +-- [처리 엔진]
```

선의 의미: 수집 계층과 객체 스토리지의 선은 다형식 원천의 객체•버전 보존 관계, 객체 스토리지와 데이터 영역의 선은 원천•검증•정제 데이터의 품질•사용 범위 분리 관계, 데이터 영역에서 갈라지는 선은 스키마•계보•접근 정책 관리와 데이터 검사•변환•분석 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 수집 계층 | 파일•로그•**변경 데이터** 수용 |
| 객체 스토리지 | 원천•정제 데이터를 **객체•버전**으로 보존 |
| 데이터 영역 | 원천•검증 데이터의 **품질•사용 범위** 분리 |
| 카탈로그•거버넌스 | **스키마•계보•접근 정책** 관리 |
| 처리 엔진 | 데이터 **검사•변환•분석** 수행 |

#### 한줄 요약

- 수집기, 객체 창고, 품질 구역, 설명 목록, 처리 도구로 구성된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **원천 객체•버전 보존**: 원본을 재현할 수 있도록 객체 키와 버전으로 저장하는 단계이다.
- **관리 메타데이터 등록**: 스키마•소유자•보존 정책을 카탈로그에 연결하는 단계이다.
- **처리 대상 발견**: 소비 목적에 맞는 위치•스키마•권한으로 데이터를 찾는 단계이다.
- **검증•정제 파일 생성**: 품질과 조회 패턴에 맞춰 형식•파티션•크기를 조정하는 단계이다.
- **계보•품질 결과 공개**: 입력•변환•산출 관계와 검증 결과를 카탈로그에 남기는 단계이다.

</details>

```text
파일•로그•변경 데이터
          |
          v
1. 원천 객체•버전 보존
          |
          v
2. 관리 메타데이터 등록
          |
          v
3. 처리 대상 발견
          |
          v
4. 검증•정제 파일 생성
          |
          v
5. 계보•품질 결과 공개
          |
          v
신뢰 수준별 데이터 제공
```

**동작 원리**

- **1. 원천 객체•버전 보존**: 재현 가능한 객체 키•버전으로 원본 저장한다.
- **2. 관리 메타데이터 등록**: 의미•소유자•보존 정책을 카탈로그에 연결한다.
- **3. 처리 대상 발견**: 위치•스키마•권한을 기준으로 데이터 탐색이다.
- **4. 검증•정제 파일 생성**: 형식•파티션•파일 크기를 조정한다.
- **5. 계보•품질 결과 공개**: 변환 관계와 검증 결과를 카탈로그에 등록한다.

#### 한줄 요약

- 원본을 그대로 보관하고 이름표•설명•품질표를 붙인 뒤 믿고 쓸 수 있는 자료를 따로 공개한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 웨어하우스(Data Warehouse)**: 정형 지표와 통합 이력을 적재 시점 스키마로 관리하는 분석 저장소이다.
- **레이크하우스(Lakehouse)**: 객체 스토리지 위에 개방 테이블 형식과 트랜잭션 메타데이터를 결합한 분석 구조이다.
- **원자성•일관성•격리성•지속성(Atomicity, Consistency, Isolation, Durability, ACID)**: 트랜잭션이 보장해야 할 네 가지 속성이다.

</details>

| 분석 저장소 | 데이터 레이크 | 데이터 웨어하우스 | 레이크하우스 |
|:---|:---|:---|:---|
| 적용 기준 | 다양한 **원천 보존•재처리** | 정형 지표 기반 **이력 분석** | 객체 기반 **통합 분석** |
| 핵심 특징 | **스키마 온 리드•객체 파일** | **스키마 온 라이트•관리형 표** | 개방 테이블과 **ACID 메타데이터** |
| 한계 | **데이터 늪•작은 파일** 문제 | 모델 경직•**적재 지연** | 메타데이터 정리•**엔진 호환** 비용 |


#### 한줄 요약

- 레이크는 원본 창고, 웨어하우스는 정리된 분석 장부, 레이크하우스는 창고 위에 장부 규칙을 더한 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **목록 조회**: 저장소의 객체 키와 메타데이터를 열거하는 작업이다.
- **작업 생성**: 입력 파일별 처리 태스크를 계획하는 단계이다.
- **승격 기준**: 원천 데이터를 검증•정제 영역으로 옮길 품질 조건이다.
- **관리 책임**: 데이터 승격을 승인하고 운영할 주체이다.
- **데이터 카탈로그**: 데이터의 위치•스키마•소유자•계보•권한을 등록해 발견성과 책임성을 제공하는 목록이다.
- **파일 병합**: 작은 객체를 적정 크기의 파일로 묶어 목록 조회와 작업 계획 비용을 줄이는 처리한다.
- **데이터 계약**: 생산자와 소비자가 합의한 스키마•품질 약속이다.
- **계약 검증**: 데이터가 계약 조건을 충족하는지 검사하는 통제이다.
- **오류 격리**: 계약 위반 데이터를 별도 영역에 보관하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 원천•검증 데이터가 섞이면 **신뢰 수준** 식별 불가 | 영역별 **승격 기준•관리 책임** 명시 | 데이터의 **사용 가능 범위** 구분 |
| 소유자•스키마•계보가 없으면 **데이터 탐색** 실패 | **데이터 카탈로그**에 관리 메타데이터 등록 | 데이터의 **발견성•책임성** 향상 |
| 작은 파일이 누적되면 **목록 조회•작업 생성** 비용 증가 | 수집 배치와 **파일 병합** 적용 | **메타데이터•작업 계획** 비용 감소 |
| 품질 검사 없이 원천을 공개하면 **데이터 늪** 형성 | **데이터 계약•검증•격리** 적용 | 검증 영역의 **데이터 신뢰도** 유지 |

#### 한줄 요약

- 날짜 서랍과 적당한 파일 묶음을 만들면 필요한 기간만 빠르게 읽을 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **운영 조건**: 원본 재처리에 필요한 카탈로그와 품질 구역의 결합한다.

</details>

- 원본 재처리가 핵심이면 **카탈로그•품질 구역**을 갖춘 **데이터 레이크** 구축이 핵심이다.

#### 한줄 요약

- 많이 모으는 것보다 무엇인지 찾고 믿고 다시 쓸 수 있게 관리하는 것이 핵심이다.
