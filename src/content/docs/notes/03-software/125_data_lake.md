## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 레이크(Data Lake)**: 정형, 반정형(JSON, 로그), 비정형(이미지, 영상) 데이터를 원시 형태(Raw Format) 그대로 저비용 객체 스토리지(S3/GCS)에 수용하는 중앙 저장소.
- **Schema-on-Read**: 적재 시점에 스키마를 강제하지 않고 원본 그대로 저장한 후, 분석가가 조회(Read)하는 시점에 스키마를 정의하여 해석하는 패러다임.

</details>

- 정의/개념: 정형·비정형 데이터를 가공 없이 객체 스토리지에 저장하고 **Schema-on-Read 기반으로 다양한 분석 및 AI/ML 학습을 지원**하는 중앙 데이터 집적소
- 배경/필요성: 전통적 DW의 Schema-on-Write 방식 적용 시 발생하는 **비정형 로그·이미지 수집 불가, 사전 ETL 병목 및 원본 데이터 유실 위험** 직면

#### 한줄 요약

- 모든 형태의 원시 데이터를 저비용 객체 스토리지에 유연하게 저장하고 읽기 시점에 스키마를 바인딩하여 분석

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 늪(Data Swamp)**: 메타데이터 관리와 거버넌스 없이 무분별하게 원시 파일만 쌓아 검색과 재사용이 불가능해지는 안티패턴.
- **메달리온 아키텍처(Medallion Architecture)**: Bronze(Raw 원시 수집) $\to$ Silver(정제 및 조인) $\to$ Gold(비즈니스 분석 마트)의 3단계 품질 계층화 구조.

</details>

- 정형, 반정형, 비정형 데이터를 원본 포맷 그대로 수용하는 **다형성 데이터 적재**
- 스키마 정의 없이 고속 적재 후 분석 시 해석하는 **Schema-on-Read 적용**
- 클라우드 객체 스토리지 기반의 **컴퓨팅과 스토리지 완전 분리(Decoupled)** #### 한줄 요약

- 가성비 높은 객체 스토리지와 Schema-on-Read를 통해 데이터 유실 없이 유연한 데이터 분석 및 AI 모델링을 지원

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Bronze / Silver / Gold 계층**: 데이터 정제도에 따라 원시 데이터(Bronze), 필터링/표준화 데이터(Silver), 최종 비즈니스 집계 데이터(Gold)로 분류.

</details>

```text
[ 데이터 레이크 메달리온 아키텍처 및 카탈로그 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      Data Lake Medallion Architecture                  │
 ├────────────────────────────────────────────────────────────────────────┤
 │ [다양한 원천 시스템] ──► [ Bronze Zone (Raw Ingestion) ]                │
 │ (Logs, RDBMS, IoT)        - 원본 데이터 그대로 보존 (JSON, CSV, 이미지)│
 │                                   │                                    │
 │                                   ▼ (정제, 중복제거, 표준화)            │
 │                          [ Silver Zone (Cleaned & Filtered) ]          │
 │                           - Parquet 열 지향 포맷 변환                  │
 │                                   │                                    │
 │                                   ▼ (비즈니스 집계, 마트 구축)         │
 │                          [ Gold Zone (Curated Business Analytics) ]    │
 │                           - BI 대시보드 및 AI/ML 특화 피처 세트        │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 전사 거버넌스 및 메타데이터 관리: Data Catalog (AWS Glue / Apache Atlas)│
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 원천 데이터를 Bronze(Raw) 수집 후 Silver(정제) 및 Gold(분석마트) 3단계 영역으로 정제 관리하는 계층형 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 브론즈 계층 (Bronze) | 다양한 원천으로부터 수집된 원시(Raw) 데이터를 **가공 없이 시계열 스냅샷으로 영구 보존** |
| 실버 계층 (Silver) | 중복 제거, 결측치 보정, 파티셔닝을 거쳐 **정제된 Parquet 포맷으로 변환 관리** |
| 골드 계층 (Gold) | 비즈니스 도메인에 맞추어 고도화된 집계 테이블을 생성하여 **BI 및 AI 모델에 즉시 제공** |
| 데이터 카탈로그 (Catalog) | 스키마, 저장 위치, 소유권, 데이터 리니지(Lineage)를 관리하여 **데이터 늪(Data Swamp) 방지** |

#### 한줄 요약

- 브론즈(원시), 실버(정제), 골드(집계) 계층과 데이터 카탈로그가 유기적으로 연계

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 레이크 수집 및 분석 5단계 파이프라인**: 원본 적재 $\to$ 카탈로그 등록 $\to$ 실버 정제 $\to$ 골드 집계 $\to$ Schema-on-Read 조회.

</details>

```text
[ 데이터 레이크 수집 및 메달리온 정제 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 원시 데이터 객체 스토리지(S3) 적재  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 데이터 카탈로그 메타데이터 자동 등록│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 분산 엔진(Spark) 기반 실버 정제 승격│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 골드 분석용 집계 테이블 구축       │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. Athena/Presto 쿼리 엔진 조회 서빙   │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 원본 적재: IoT 센서 로그, RDBMS 변경 로그, 이미지를 S3 Bronze 버킷에 원본 그대로 적재.
2. 카탈로그 등록: AWS Glue Crawler 또는 Apache Atlas가 새로운 데이터 파티션과 스키마를 탐색하여 카탈로그에 등록.
3. 실버 정제: Apache Spark 잡을 통해 이상치 제거, 스키마 검증, Parquet 압축을 거쳐 Silver 계층으로 승격.
4. 골드 집계: 최종 비즈니스 KPI 및 분석 요건에 맞추어 일별/월별 집계 테이블을 Gold 계층에 생성.
5. 조회 서빙: 분석가가 Presto나 Trino, Amazon Athena를 통해 Schema-on-Read 방식으로 SQL 쿼리를 실행.

#### 한줄 요약

- 원본 적재 $\to$ 카탈로그 등록 $\to$ 실버 정제 $\to$ 골드 집계 $\to$ 조회 서빙의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DW vs Data Lake**: 고성능 정형 SQL 분석 전용 저장소인 DW와 무제한 다형성 원시 데이터 집적소인 Data Lake.

</details>

| 구분 | 데이터 웨어하우스 (Data Warehouse) | 데이터 레이크 (Data Lake) |
|:---|:---|:---|
| **적용 기준** | 고성능 경영 지표 BI, 재무 회계 보고서 | AI/ML 모델 학습, 대규모 원시 로그 보존, 탐색적 분석 |
| **핵심 특징** | **Schema-on-Write, 정형 데이터 전용, 고속 OLAP** | **Schema-on-Read, 정형·반정형·비정형 수용, 저비용 S3** |
| **한계** | 비정형 데이터 저장 불가 및 고가의 스토리지 비용 | 메타데이터 관리 부재 시 Data Swamp(데이터 늪) 전락 |

#### 한줄 요약

- 정형 지표 분석은 DW, 대규모 원시 보존과 AI 머신러닝 학습은 Data Lake를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Small File 문제**: S3에 수 킬로바이트(KB) 크기의 자잘한 파일이 수백만 개 쌓여 메타데이터 조회(List API) 및 쿼리 병목을 유발하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거버넌스 부재로 검색과 활용이 마비되는 Data Swamp(데이터 늪) | **AWS Glue / Apache Atlas 데이터 카탈로그 및 메타데이터 등록 의무화** | 데이터 검색성 및 리니지 투명성 확보 |
| 수백만 개의 자잘한 Small File로 인한 S3 목록 조회 병목 | **Spark 백그라운드 컴팩션(Compaction) 작업으로 128MB~512MB 파일 병합** | 쿼리 스캔 성능 10배 이상 가속 |
| S3 Key 파티셔닝 부재로 인한 전체 스토리지 풀 스캔 비용 과다 | **S3 Key를 `year=YYYY/month=MM/day=DD` 파티션 구조로 설계** | 쿼리 비용 및 파티션 프루닝 최적화 |

#### 한줄 요약

- 카탈로그 등록, Small File 컴팩션 병합, 날짜 파티셔닝 설계를 통해 데이터 늪화를 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **데이터 레이크하우스로의 진화(Lakehouse Evolution)**: Data Lake의 저비용 객체 스토리지 위에 ACID 트랜잭션과 고성능 인덱싱을 얹은 차세대 통합 아키텍처.

</details>

- **데이터 레이크** 기반 빅데이터와 AI 시대의 원천 자산을 보존하는 필수 인프라이며, 체계적인 메달리온 정제 아키텍처와 전사 데이터 카탈로그 거버넌스를 결합하여 고부가가치 AI/ML 플랫폼으로 발전시켜야 함

#### 한줄 요약

- 객체 스토리지와 Schema-on-Read를 기반으로 정형·비정형 원본을 보존하고 데이터 거버넌스를 확립
