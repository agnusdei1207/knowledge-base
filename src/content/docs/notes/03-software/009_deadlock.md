## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **영구 동결 및 4대 제어 기법(Deadlock Control Strategies)**: 프로세스가 자원을 놓지 못하고 무한 대기하는 교착 상태를 예방(Prevention), 회피(Avoidance), 탐지(Detection), 복구(Recovery)로 제어하는 전략.
- **코프만 4대 조건(Coffman 4 Conditions)**: 상호 배제, 점유 대기, 비선점, 환형 대기가 동시에 성립할 때 교착 상태가 발생하는 필요 조건.

</details>

- 정의/개념: 복수의 프로세스가 서로 상대방이 점유한 자원을 무한 대기함에 따라 **실행 흐름이 영구 동결되는 시스템 이상 현상 및 4대 제어 기법**
- 배경/필요성: 멀티스레드 공유 자원 동시 획득 시 발생하는 **코프만 4대 조건(상호배제·점유대기·비선점·환형대기) 충족 및 영구 교착** 직면

#### 한줄 요약

- 4개의 코프만 조건이 동시 성립할 때 발생하는 교착 상태를 예방·회피·탐지·복구 4단계 전략으로 통제

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상호 배제(Mutual Exclusion)**: 자원이 한 번에 하나의 프로세스만 사용할 수 있는 배타적 접근 속성.
- **점유 대기(Hold & Wait)**: 프로세스가 자원을 보유한 채로 추가 자원을 기다리는 상태.
- **비선점(No Preemption)**: 프로세스가 보유 중인 자원을 강제로 회수할 수 없는 속성.
- **환형 대기(Circular Wait)**: 프로세스들이 원형으로 서로 상대방의 자원을 기다리는 대기 사이클.

</details>

- **코프만 4조건**(상호 배제·점유 대기·비선점·환형 대기)이 동시에 성립할 때만 교착 상태 발생
- **자원 할당 그래프**의 사이클 존재로 단일 인스턴스 자원의 교착 상태 판정
- 예방·회피·탐지·복구 4단계 전략으로 교착 상태 통제

#### 한줄 요약

- 코프만 4조건 중 하나 이상을 제거하거나, 사이클 탐지 후 복구하여 교착 상태를 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대기 그래프(Wait-for Graph)**: 자원 할당 그래프에서 자원 노드를 제거하고 프로세스 간 대기 관계만 표현한 단순화 그래프로, 사이클 탐지로 교착 상태를 탐지.

</details>

```text
[ 교착 상태 방어 구조 ]
자원 관리자 (할당·요청 기록)
├─ 예방 규칙 (설계 단 코프만 조건 배제)
│   └─ Lock Ordering·비선점 자원 해제
├─ 안전성 검사 (회피)
│   └─ 은행가 알고리즘: 안전 상태 검증 후 할당
└─ 탐지·복구
    ├─ 대기 그래프 사이클 탐지
    └─ 희생자 선정 후 자원 회수·롤백
```

선의 의미: 가지(`├─`, `└─`)는 예방·회피·탐지·복구의 방어 전략 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 자원 관리자 | 프로세스의 자원 할당·요청 상태 기록 |
| 예방 규칙 | 설계 단에서 **코프만 조건** 중 하나 이상 배제 |
| 안전성 검사기 | **은행가 알고리즘**으로 자원 할당 전 안전 상태 검증 |
| 대기 그래프 | 주기적 사이클 탐지로 교착 상태 탐지 |
| 복구 관리자 | 희생자 프로세스 선정 후 자원 회수·롤백 수행 |

#### 한줄 요약

- 자원 관리자가 할당·요청을 기록하고, 예방·회피·탐지·복구 메커니즘이 교착 상태를 계층적으로 방어

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **은행가 알고리즘(Banker's Algorithm)**: 자원 할당 시 최대 요구량까지 안전하게 완료할 수 있는 순서(안전 순서열)가 존재하는지 검증하여 안전 상태에서만 자원을 할당하는 회피 알고리즘.

</details>

```text
자원 요청 발생
   │
   ▼
1. 예방 가능 여부 판정
├─ 가능: Lock Ordering·비선점 자원 해제 규칙 적용
└─ 불가
      │
      ▼
   2. 최대 요구량 예측 가능 여부 판정 (회피)
   ├─ 가능: 은행가 알고리즘으로 안전 상태 검증 후 할당
   └─ 불가
         │
         ▼
      3. 탐지 및 복구
      ├─ 주기적 대기 그래프 사이클 탐지
      └─ 사이클 발견 시 희생자 선정·자원 회수·롤백
```

**동작 원리**

1. **예방 판정**: 설계 단에서 Lock Ordering으로 환형 대기를 차단하거나 비선점 자원 해제로 비선점 조건을 제거
2. **회피 적용**: 최대 요구량 정보를 확보한 경우 **은행가 알고리즘**으로 안전 순서열 존재 여부 검증 후 할당
3. **탐지 및 복구**: 예방·회피 불가 시 주기적으로 대기 그래프 사이클을 탐지하고 교착 상태 발생 후 희생자 선정·롤백

#### 한줄 요약

- 예방→회피→탐지 순으로 전략을 적용하고, 탐지된 교착 상태는 희생자 롤백으로 복구

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **안전 상태(Safe State)**: 모든 프로세스가 자원을 순차적으로 획득·해제하며 완료할 수 있는 안전 순서열이 하나 이상 존재하는 시스템 상태.

</details>

| 비교 항목 | 예방 (Prevention) | 회피 (Avoidance) | 탐지·복구 (Detection & Recovery) |
|:---|:---|:---|:---|
| 적용 기준 | 코프만 조건 제거가 설계 단에서 가능한 경우 | 최대 자원 요구량 예측이 가능한 경우 | 예방·회피 모두 불가하며 교착 상태 발생 빈도가 낮은 경우 |
| 핵심 기법 | **Lock Ordering**·비선점 자원 해제 | **은행가 알고리즘** 기반 **안전 상태** 검증 | **대기 그래프** 사이클 탐지 후 희생자 롤백 |
| 한계 및 위험 | 자원 활용률 저하 및 설계 제약 증가 | 할당 요청마다 안전 순서열 계산 오버헤드 | 교착 상태 발생 후 롤백 비용 발생 |

#### 한줄 요약

- 예방은 설계 제약을 수반하고, 회피는 계산 오버헤드가 크며, 탐지·복구는 빠르지만 롤백 비용 발생

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **락 오더링(Lock Ordering)**: 모든 잠금에 전역 획득 순서를 부여하여 환형 대기 사이클 형성을 원천 차단하는 예방 기법.
- **tryLock/타임아웃(tryLock with Timeout)**: 잠금 획득을 제한 시간 동안만 시도하고 실패 시 보유 자원을 해제하여 점유 대기 조건을 제거하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복수 잠금의 비일관적 획득 순서로 **환형 대기** 형성 | 전역 **락 오더링** 규칙 강제 적용 | 환형 대기 사이클 생성 원천 차단 |
| 잠금 대기 중 자원을 무한 보유하는 **점유 대기** 지속 | **tryLock/타임아웃**으로 실패 시 보유 자원 전체 해제 | 점유 대기 조건 해소 및 교착 상태 예방 |
| 분산 환경에서 네트워크 파티션으로 잠금 해제 불가 | 펜싱 토큰·잠금 임대(Lease) 만료로 자동 해제 | 분산 잠금 교착 상태 자동 복구 |

#### 한줄 요약

- 환형 대기는 락 오더링으로, 점유 대기는 tryLock 타임아웃으로, 분산 잠금은 펜싱 토큰으로 예방

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **교착 상태 대응 선택 기준**: 자원 할당 예측 가능성과 롤백 비용 수용성 중 우선 제약에 따라 예방·회피·탐지·복구를 결정하는 판단 기준.

</details>

- 일반 애플리케이션은 **락 오더링 기반 예방**, 롤백 비용 수용 가능한 DB 환경은 **탐지·복구** 선택

#### 한줄 요약

- 예방 가능하면 락 오더링으로 선제 차단하고, 예방 불가한 DB 환경은 탐지 후 롤백으로 복구
