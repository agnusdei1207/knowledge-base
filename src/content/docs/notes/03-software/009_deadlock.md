## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **교착상태(Deadlock)**: 여러 프로세스가 서로 보유한 자원을 기다리는 순환 때문에 모두 진행하지 못하는 동시성 실패 상태
- **환형 대기(Circular Wait)**: 각 프로세스가 다음 프로세스의 보유 자원을 기다리는 관계가 닫힌 순환을 이루는 조건

</details>

- 정의/개념: 서로 보유한 자원을 기다리는 순환으로 모든 프로세스가 멈추는 **동시성 실패 상태**
- 배경/필요성: 잠금 순서 없이 여러 자원을 점유하면 **환형 대기**로 영구 정지

#### 한줄 요약

- 두 사람이 상대방 열쇠를 쥔 채 서로 돌려주기만 기다리면 누구도 다음 일을 시작하지 못한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상호 배제·점유와 대기·비선점·환형 대기**: 교착상태가 성립하려면 동시에 충족해야 하는 네 필요조건
- **자원 할당 그래프(Resource-allocation Graph)**: 프로세스 요청과 자원 할당 관계를 방향 간선으로 표현한 그래프

</details>

- **상호 배제·점유와 대기**로 자원 보유 중 추가 요청 차단
- **비선점·환형 대기**가 결합하면 순환 내 프로세스 진행 정지
- **자원 할당 그래프 순환**으로 교착 후보 탐지

#### 한줄 요약

- 자원을 혼자 쓰고 쥔 채 기다리며 빼앗을 수도 없는 상태가 원을 이룰 때 모두 멈춘다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **대기 그래프(Wait-for Graph)**: 프로세스가 어느 자원 보유자를 기다리는지 방향 간선으로 표현한 그래프
- **자원 관리자(Resource Manager)**: 자원 할당·요청·반납 상태를 기록하고 대기 순환을 탐지하는 구성요소
- **로그·복구점(Log·Recovery Point)**: 변경 이력과 되돌릴 수 있는 이전 상태를 보관하는 복구 자료
- **희생 선택기(Victim Selector)**: 교착 순환에서 롤백 비용과 재시도 횟수를 비교해 중단할 작업을 정하는 구성요소

</details>

```mermaid
block
    columns 1
    P["프로세스"]
    block:D["교착 통제 경계"]
        columns 2
        R["자원 관리자"]
        G["대기 그래프"]
        V["희생 선택기"]
        L["로그·복구점"]
    end
    P --- R
    R --- G
    G --- V
    V --- L
```

| 구성요소 | 책임 |
|:---|:---|
| 프로세스 | **자원 보유·추가 요청** |
| 자원 관리자 | **할당·대기 관계 기록** |
| 대기 그래프 | **환형 대기 탐지** |
| 희생 선택기 | **복구 대상 결정** |
| 로그·복구점 | **미완료 변경 복구** |

#### 한줄 요약

- 서로의 열쇠를 기다리는 원을 찾은 뒤 되돌리기 비용이 작은 작업 하나를 복구점으로 돌려 열쇠를 푼다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **희생 트랜잭션(Victim Transaction)**: 교착 순환을 끊기 위해 선택해 이전 복구점으로 롤백하는 작업
- **롤백(Rollback)**: 작업 상태를 이전 복구점으로 되돌려 보유 자원을 해제하는 처리
- **재시도(Retry)**: 롤백된 작업을 자원이 해제된 뒤 처음이나 안전한 복구점부터 다시 실행하는 처리

</details>

```mermaid
sequenceDiagram
    participant P as 경쟁 프로세스
    participant R as 자원 관리자
    participant G as 대기 그래프
    P->>R: 1. 자원 요청 관계
    R->>G: 2. 대기 간선
    G-->>R: 3. 순환 경로
    R->>R: 4. 희생 트랜잭션 선택
    R->>P: 5. 롤백·자원 회수
    R-->>P: 재시도 통지
```

**동작 원리**

1. **자원 요청 관계**: 프로세스별 보유 자원과 추가 요청 기록
2. **대기 간선**: 자원 보유자를 향하는 프로세스 간 의존성 생성
3. **순환 경로**: 닫힌 대기 의존성을 교착 후보로 판정
4. **희생 트랜잭션 선택**: 진행량·롤백 비용·재시도 횟수를 비교해 복구 대상 결정
5. **롤백·자원 회수**: 선택 작업을 복구점으로 되돌려 순환 자원 해제

#### 한줄 요약

- 서로 기다리는 원을 찾고 비용이 작은 작업을 되돌린다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **예방·회피·탐지·복구**: 필요조건 제거, 안전 상태 검사, 발생 후 순환 탐지와 롤백으로 교착을 통제하는 세 방식
- **안전 상태(Safe State)**: 모든 프로세스를 완료시킬 자원 할당 순서가 존재하는 상태

</details>

| 교착 대응 방식 | 예방 | 회피 | 탐지·복구 |
|:---|:---|:---|:---|
| 적용 기준 | 획득 순서·**선점 규칙 강제 가능** | 최대 요구량 **사전 파악 가능** | 발생이 드물고 **롤백 가능** |
| 핵심 특징 | 필요조건 **하나 이상 제거** | 안전 상태일 때만 **자원 할당** | 순환 탐지 후 **종료·롤백** |
| 한계 | 자원 이용률 **저하** | 사전 정보·**검사 비용** | 탐지 전 **서비스 정지** |

> 요약: 조건 제거는 **예방**, 안전 상태 검사는 **회피**, 사후 순환 해소는 탐지·복구

#### 한줄 요약

- 순서를 강제할 수 있으면 예방하고, 최대 요구량을 알면 회피하며, 되돌릴 수 있으면 발생 후 복구한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **전역 잠금 획득 순서(Global Lock Ordering)**: 모든 코드가 잠금을 같은 순서로 획득해 환형 대기를 제거하는 규칙
- **정적 분석(Static Analysis)**: 프로그램을 실행하지 않고 잠금 획득 순서와 잠재 순환을 검사하는 기법
- **상관 식별자(Correlation Identifier)**: 여러 시스템을 지나는 하나의 요청 흐름을 연결해 추적하는 공통 값
- **임대·펜싱 토큰(Lease·Fencing Token)**: 잠금 유효시간과 증가 번호로 만료된 소유자의 뒤늦은 쓰기를 차단하는 방식
- **희생 정책(Victim Policy)**: 진행량·롤백 비용·재시도 이력으로 교착 해소 대상을 고르는 기준

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 코드 경로마다 잠금 획득 순서가 달라 **환형 대기 형성** | **전역 잠금 획득 순서**와 정적 분석 적용 | **환형 대기 조건** 제거 |
| 시간 제한만 사용해 교착과 **장기 작업 혼동** | 대기 그래프·잠금 보유자·**자원 요청 경로** 수집 | **교착 순환** 원인 판별 |
| 같은 희생 작업을 반복 선택해 **기아 발생** | 롤백 비용·재시도 횟수를 반영한 **희생 정책** | 작업별 **복구 공정성** 향상 |
| 외부 자원·분산 잠금이 빠져 **대기 관계 누락** | 전 구간 상관 식별자와 **임대·펜싱 토큰** 적용 | 숨은 대기와 **중복 소유** 통제 |

#### 한줄 요약

- 데이터베이스는 서로 기다리는 거래 중 하나를 이전 상태로 되돌려 나머지가 진행하게 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **예방·회피·탐지·복구**: 순서 강제 가능성, 최대 요구량 파악, 롤백 가능성에 따라 고르는 교착 대응 방식

</details>

- 순서 강제는 **예방**, 최대 요구량 파악은 회피, 롤백 가능은 **탐지·복구** 선택

#### 한줄 요약

- 잠금 순서를 강제할 수 있는지, 최대 요청량을 아는지, 되돌리기 비용이 작은지에 따라 대응법을 선택한다.
