## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **교착상태(Deadlock)**: 여러 프로세스가 서로 보유한 자원을 기다리는 순환 때문에 모두 진행하지 못하는 동시성 실패 상태이다.
- **환형 대기(Circular Wait)**: 각 프로세스가 다음 프로세스의 보유 자원을 기다리는 관계가 닫힌 순환을 이루는 조건이다.

</details>

- 정의/개념: **교착상태**는 서로 보유한 자원을 기다리는 순환으로 모든 프로세스가 멈추는 동시성 실패 상태이다.
- 배경/필요성: 잠금 순서 없이 여러 자원을 점유하면 **환형 대기**로 영구 정지가 발생한다.

#### 한줄 요약

- 상호배제(Mutual Exclusion), 점유대기(Hold and Wait), 비선점(No Preemption), 환형대기(Circular Wait) 4가지 필요조건이 동시 충족될 때 발생하는 정지 상태이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상호 배제(Mutual Exclusion)**: 한 자원을 한 프로세스만 사용하는 조건이다.
- **점유와 대기(Hold and Wait)**: 자원을 보유한 채 다른 자원을 기다리는 조건이다.
- **비선점(No Preemption)**: 보유 자원을 강제로 회수할 수 없는 조건이다.
- **자원 할당 그래프(Resource-allocation Graph)**: 프로세스 요청과 자원 할당 관계를 방향 간선으로 표현한 그래프이다.

</details>

- **상호 배제**와 **점유와 대기**로 자원 보유 중 추가 요청이 차단된다.
- **비선점**과 **환형 대기**가 결합하면 순환 내 프로세스가 진행하지 못한다.
- **자원 할당 그래프**의 순환으로 교착 후보를 탐지한다.

#### 한줄 요약

- Resource-allocation Graph 내의 Directed Cycle 형성이 Deadlock 발생의 필요충분/필요 조건이 된다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **대기 그래프(Wait-for Graph)**: 프로세스가 어느 자원 보유자를 기다리는지 방향 간선으로 표현한 그래프이다.
- **자원 관리자(Resource Manager)**: 자원 할당•요청•반납 상태를 기록하고 대기 순환을 탐지하는 구성요소이다.
- **예방 규칙**: 잠금 순서나 선점 규칙으로 교착 필요조건을 제거하는 통제이다.
- **안전성 검사**: 요청을 허용한 뒤에도 안전 순서가 남는지 확인하는 처리이다.
- **복구 관리자**: 순환이 발견되면 희생 작업을 종료•롤백해 자원을 회수하는 구성요소이다.

</details>

```text
                 [자원 관리자]
                  /     |      \
        [예방 규칙] [안전성 검사] [대기 그래프]
                                     |
                               [복구 관리자]
```

선의 의미: 자원 관리자는 예방 규칙과 안전성 검사로 할당을 통제하고, 대기 그래프에서 순환이 발견되면 복구 관리자를 사용한다.

| 구성요소 | 책임 |
|:---|:---|
| 자원 관리자 | 할당•대기 관계 기록 |
| 예방 규칙 | 필요조건 사전 제거 |
| 안전성 검사 | 요청 후 안전 상태 판정 |
| 대기 그래프 | 환형 대기 탐지 |
| 복구 관리자 | 희생 작업 종료•롤백 |

#### 한줄 요약

- **예방 규칙**과 **안전성 검사** 및 **대기 그래프**•**복구 관리자**를 결합한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **예방 가능성 판정**: 잠금 순서나 자원 선점을 강제할 수 있는지 확인하는 단계이다.
- **예방 적용**: 네 필요조건 중 하나 이상을 제거하는 방식이다.
- **회피 가능성 판정**: 프로세스별 최대 자원 요구량을 미리 알 수 있는지 확인하는 단계이다.
- **회피 적용**: 안전 상태를 유지하는 요청만 허용하는 방식이다.
- **탐지•복구 적용**: 순환을 탐지한 뒤 희생 작업을 종료•롤백하는 방식이다.

</details>

```text
┌──────────────────────────────┐
│ 자원 할당 정책 설계         │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 예방 가능성 판정         │
└───────┬──────────────────────┘
        ├─ 가능 ─▶ [2. 예방 적용]
        │ 불가
        ▼
┌──────────────────────────────┐
│ 3. 회피 가능성 판정         │
└───────┬──────────────────────┘
        ├─ 최대 요구량 파악 가능
        │            └─▶ [4. 회피 적용]
        │ 파악 불가
        ▼
┌──────────────────────────────┐
│ 5. 탐지•복구 적용           │
│ 순환 탐지 후 종료•롤백      │
└──────────────────────────────┘
```

### 동작 원리

1. **예방 가능성 판정**: 획득 순서•선점 규칙 강제 여부를 확인한다.
2. **예방 적용**: 교착 필요조건 하나를 사전에 제거한다.
3. **회피 가능성 판정**: 최대 요구량 사전 파악 여부를 확인한다.
4. **회피 적용**: 안전 순서가 남는 자원 요청만 승인한다.
5. **탐지•복구 적용**: 순환 탐지 후 희생 작업을 종료•롤백한다.

#### 한줄 요약

- Prevention(필요조건 제거) $\rightarrow$ Avoidance(Banker's Algorithm / Safe State 유지) $\rightarrow$ Detection & Recovery(Wait-for Graph & Victim Selection) 순으로 전략을 결정한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **예방(Prevention)**: 교착 필요조건 하나를 제거하는 방식이다.
- **회피(Avoidance)**: 안전 상태를 유지하는 요청만 허용하는 방식이다.
- **탐지(Detection)**: 발생한 대기 순환을 찾아내는 방식이다.
- **복구(Recovery)**: 희생 작업을 롤백해 대기 순환을 끊는 방식이다.
- **안전 상태(Safe State)**: 모든 프로세스를 완료시킬 자원 할당 순서가 존재하는 상태이다.

</details>

| 교착 대응 방식 | 예방 | 회피 | 탐지•복구 |
|:---|:---|:---|:---|
| 적용 기준 | 획득 순서•선점 규칙 강제 가능 | 최대 요구량 사전 파악 가능 | 발생이 드물고 롤백 가능 |
| 핵심 특징 | 필요조건 하나 이상 제거 | **안전 상태**일 때만 자원 할당 | 순환 탐지 후 종료•롤백 |
| 한계 | 자원 이용률 저하 | 사전 정보•검사 비용 | 탐지 전 서비스 정지 |

> 요약: 조건 제거는 **예방**, 안전 상태 검사는 **회피**, 사후 순환 해소는 탐지•복구가 핵심이다.

#### 한줄 요약

- Lock Order Enforcement는 Prevention, Max Resource Claim 파악은 Avoidance(Banker's Algorithm)를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **전역 잠금 획득 순서(Global Lock Ordering)**: 모든 코드가 잠금을 같은 순서로 획득해 환형 대기를 제거하는 규칙이다.
- **정적 분석(Static Analysis)**: 프로그램을 실행하지 않고 잠금 획득 순서와 잠재 순환을 검사하는 기법이다.
- **상관 식별자(Correlation Identifier)**: 여러 시스템을 지나는 하나의 요청 흐름을 연결해 추적하는 공통 값이다.
- **임대(Lease)**: 잠금 소유권에 유효시간을 두는 방식이다.
- **펜싱 토큰(Fencing Token)**: 증가 번호로 만료 소유자의 쓰기를 차단하는 값이다.
- **희생 정책(Victim Policy)**: 진행량•롤백 비용•재시도 이력으로 교착 해소 대식을 고르는 기준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 코드 경로마다 잠금 획득 순서가 달라 **환형 대기** 형성 | **전역 잠금 획득 순서**와 **정적 분석** 적용 | 환형 대기 조건 제거 |
| 시간 제한만 사용해 교착과 장기 작업 혼동 | **대기 그래프**•잠금 보유자•자원 요청 경로 수집 | 교착 순환 원인 판별 |
| 같은 희생 작업을 반복 선택해 기아 발생 | 롤백 비용•재시도 횟수를 반영한 **희생 정책** | 작업별 복구 공정성 향상 |
| 외부 자원•분산 잠금이 빠져 대기 관계 누락 | 전 구간 **상관 식별자**와 **임대**•**펜싱 토큰** 적용 | 숨은 대기와 중복 소유 통제 |

#### 한줄 요약

- Lock Hierarchy / Global Lock Ordering을 통한 Prevention과 Lock Timeout / Fencing Token 기반 분산 Deadlock 복구 기법을 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **순서 강제 가능성**: 잠금 순서를 통제할 수 있으면 예방을 고르는 기준이다.
- **최대 요구량 파악**: 자원 상한을 알면 회피를 고르는 기준이다.
- **롤백 가능성**: 작업을 되돌릴 수 있으면 탐지•복구를 고르는 기준이다.
- **교착 대응 선택 기준**: 순서 통제와 최대 요구량 파악 및 롤백 가능성에 따라 대응법을 고르는 기준이다.

</details>

- **교착 대응 선택 기준**에 따라 **순서 강제 가능성**이 있으면 **예방**, **최대 요구량 파악**이 가능하면 **회피**, **롤백 가능성**이 있으면 **탐지**와 **복구**를 선택한다.

#### 한줄 요약

- Control Overhead vs Resource Utilization Trade-off 분석에 의거하여 예방, 회피, 탐지/복구 기법을 산정한다.
