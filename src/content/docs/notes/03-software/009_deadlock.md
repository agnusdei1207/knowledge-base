## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **교착상태(Deadlock)**: 2개 이상의 프로세스가 서로 상대방이 차지하고 있는 자원을 무한정 기다리며 실행이 영구 중단되는 현상.
- **코프만 4대 조건(Coffman Conditions)**: 상호 배제, 점유 대기, 비선점, 환형 대기가 동시에 성립할 때 발생하는 교착상태의 필요충분조건.

</details>

- 정의/개념: 복수 프로세스가 서로의 자원을 무한 대기하여 시스템이 멈추는 현상과 이를 통제하는 **교착상태 4대 제어 기법**
- 배경/필요성: 다중 프로그래밍 환경에서 **코프만 4대 조건 성립에 따른 시스템 영구 동결 및 가용성 마비 해결 불가**

#### 한줄 요약
- 코프만 4조건을 무력화하거나 탐지 후 롤백하여 교착상태를 체계적으로 제어한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상호 배제(Mutual Exclusion)**: 한 번에 프로세스 하나만 자원을 독점 사용하는 성질.
- **점유 대기(Hold & Wait)**: 자원을 쥔 채로 다른 자원을 추가 요구하며 대기하는 성질.
- **비선점(No Preemption)**: 다른 프로세스가 사용 중인 자원을 강제로 뺏을 수 없는 성질.
- **환형 대기(Circular Wait)**: 대기 프로세스 간에 원형 순환 고리(Cycle)가 형성되는 성질.

</details>

- **코프만 4대 조건**(상호 배제·점유 대기·비선점·환형 대기)이 동시 성립할 때만 발생
- 자원 할당 그래프(RAG) 상의 **환형 사이클(Cycle)** 분석으로 발생 여부 수학적 판정
- 예방(Prevention), 회피(Avoidance), 탐지(Detection), 복구(Recovery) 4단계 방어 전략

#### 한줄 요약
- 4대 조건 중 하나를 제거(예방), 안전 상태 유지(회피), 또는 사이클 탐지 후 복구한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대기 그래프(Wait-for Graph)**: 자원 할당 그래프에서 자원 노드를 생략하고 프로세스 간 직접 대기 관계만 표현하여 사이클을 빠르게 검출하는 그래프.

</details>

```text
[교착상태 4단계 제어 아키텍처]
|-- 1단계: 예방 (Prevention - 설계 시 코프만 4조건 중 1개 이상 원천 제거)
|   |-- 상호 배제 제거 (공유 가능 자원화)
|   |-- 점유 대기 제거 (모든 자원 일괄 동시 요청)
|   |-- 비선점 제거 (추가 자원 획득 실패 시 보유 자원 강제 반납)
|   `-- 환형 대기 제거 (전역 락 오더링: Lock Ordering)
|-- 2단계: 회피 (Avoidance - 은행가 알고리즘 기반 안전 상태 검증)
|-- 3단계: 탐지 (Detection - 대기 그래프 DFS/Tarjan 사이클 탐지)
`-- 4단계: 복구 (Recovery - 희생자 프로세스 선정 및 자원 강제 선점/롤백)
```

선의 의미: 계층 및 방어 단계별 제어 구조

| 구성요소 | 책임 |
|:---|:---|
| 예방 모듈 | 전역 락 순서화(Lock Ordering)로 환형 대기 발생 원천 배제 |
| 회피 모듈 | **은행가 알고리즘**으로 자원 할당 후 안전 상태(Safe State) 여부를 사전 검증 |
| 탐지 모듈 | **대기 그래프(Wait-for Graph)** 상의 순환 사이클을 주기적 탐색 |
| 복구 모듈 | 최소 비용 희생자(Victim) 프로세스를 선정하여 강제 종료 및 체크포인트 롤백 |

#### 한줄 요약
- 설계 예방, 안전성 검증 회피, 대기 그래프 탐지, 희생자 롤백 복구가 단계적으로 작동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **은행가 알고리즘(Banker's Algorithm)**: 자원 요청 시 할당 후에도 모든 프로세스가 정상 종료 가능한 안전 순서열(Safe Sequence)이 존재하는지 검증하는 회피 기법.

</details>

```text
프로세스의 자원 할당 요청 인입
        │
   설계 단에서 전역 락 순서(Lock Ordering) 예방이 적용되었는가?
   ┌────┴─────┐
  예           아니오
   │             │
환형 대기 배제로  최대 자원 요구량을 사전에 파악할 수 있는가?
즉시 안전 할당    ┌────┴─────┐
   │             예           아니오 (사전 예측 불가)
   │             │             │
   │        은행가 알고리즘    일단 자원 할당 실행
   │        안전 상태 검증     │
   │        ┌────┴─────┐      주기적으로 대기 그래프(Wait-for Graph)
   │       안전        불안전    사이클 탐지 수행
   │        │          │       │
   │     자원 할당   요청 대기  교착 사이클 발견 시
   │        │        (회피)    희생자 선정 후 자원 회수 및 롤백
   └────┬───┴──────────┴───────┘
        │
   프로세스 실행 정상 완료
```

#### 한줄 요약
- 락 오더링 예방 → 은행가 안전성 회피 → 런타임 사이클 탐지 및 롤백 복구 순으로 제어한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **타조 알고리즘(Ostrich Algorithm)**: 교착상태 발생 빈도가 극히 낮고 해결 비용이 클 때 문제를 무시하고 시스템을 재부팅하는 실용적 방식 (UNIX/Windows 채택).

</details>

| 제어 방식 | 예방 (Prevention) | 회피 (Avoidance) | 탐지 및 복구 (Detection) | 타조 알고리즘 (Ostrich) |
|:---|:---|:---|:---|:---|
| 자원 할당 시점 | 조건 제한 하에 즉시 할당 | **안전 상태 검증 후 할당** | 즉시 할당 후 사후 검사 | 무조건 즉시 할당 |
| 오버헤드 | **자원 낭비 및 처리량 저하** | 매 요청 시 $O(M \times N^2)$ 계산 | 탐지 알고리즘 및 롤백 비용 | **오버헤드 0** |
| 사전 지식 | 없음 | **프로세스별 최대 요구량** | 없음 | 없음 |
| 주요 적용처 | 임베디드 락 설계, OS 내부 | 특수 목적 배치 시스템 | RDBMS 트랜잭션 엔진 | 범용 운영체제 (Linux, Windows) |

#### 한줄 요약
- 일반 락은 락 오더링 예방, RDBMS는 탐지 및 롤백, 범용 OS는 타조 알고리즘을 실용적으로 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **락 오더링(Lock Ordering)**: 시스템 내 모든 뮤텍스에 고유 ID 번호를 부여하고 오름차순으로만 락을 획득하도록 강제하는 예방 기법.
- **tryLock 타임아웃**: 락을 무한정 기다리지 않고 지정 시간 경과 시 실패를 반환하고 보유 락을 모두 해제하는 점유 대기 방지 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다중 뮤텍스 획득 순서 불일치로 **환형 대기** 발생 | 전역 **락 오더링(Lock Ordering)** 규칙 엄격 적용 | 환형 대기 조건 원천 차단 및 데드락 예방 |
| 락 획득 실패 후 무한 대기로 인한 **점유 대기** 지속 | **`tryLock()` 타임아웃** 적용 및 실패 시 보유 락 전체 해제 | 점유 대기 조건 해소 및 자원 즉시 양보 |
| RDBMS 트랜잭션 간 교착상태 발생 | 트랜잭션 타임아웃 및 **대기 그래프 사이클 탐지 롤백** | 교착 트랜잭션 자동 해소 및 데이터 일관성 유지 |
| 분산 환경에서 네트워크 단절 시 분산 락 고착 | 분산 락(Redlock) **TTL(Time-To-Live) 임대 만료** 설정 | 노드 다운 시에도 락 자동 해제 및 시스템 복구 |

#### 한줄 요약
- 락 오더링, tryLock 타임아웃, RDBMS 사이클 롤백, 분산 락 TTL로 교착상태를 완벽 방어한다.

## Ⅶ. 결론

- 소프트웨어는 **락 오더링**, DB는 **대기 그래프 롤백** 선택

#### 한줄 요약
- 교착상태는 코프만 조건 제거를 통한 선제적 예방과 RDBMS의 자동 탐지·롤백 메커니즘을 상황에 맞게 최적 배치해야 한다.
