## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **마스터 데이터 관리(Master Data Management, MDM)**: 여러 원천의 고객•상품 같은 공통 개체를 식별•정합•통합해 신뢰할 기준정보로 배포하는 관리 체계이다.

</details>

- 정의/개념: 여러 원천의 고객•상품 같은 공통 개체를 식별•정합•통합하여 신뢰할 기준정보로 배포하는 **마스터 데이터 관리(Master Data Management, MDM)** 체계
- 배경/필요성: 원천별 키•속성 차이로 **고객 중복 집계•상품 기준 불일치** 발생

#### 한줄 요약

- 여러 장부의 같은 사람이나 상품을 찾아 하나의 기준 신분표로 연결한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **생존 규칙**: 원천 신뢰도•최신성•완전성으로 속성별 기준값을 결정하는 규칙이다.
- **표준화•매칭**: 원천별 형식•코드를 통일하고 레코드가 같은 개체인지 판정하는 활동이다.
- **교차 매핑**: 중앙 기준 식별자와 각 원천 시스템의 로컬 키를 연결한 관계이다.

</details>

- **표준화•매칭** 으로 원천 형식을 통일하고 동일 개체 판정
- **생존 규칙** 으로 속성별 신뢰 원천과 기준값 결정
- **교차 매핑** 으로 기준 식별자와 원천별 로컬 키 연결

#### 한줄 요약

- 비슷하다고 무조건 합치지 않고 값의 우선순위와 애매한 경우의 사람 검토가 필요하다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **매칭•병합 엔진**: 후보 레코드를 줄이고 동일 개체 여부와 통합 결과를 판정하는 구성요소이다.
- **마스터 데이터 관리(Master Data Management, MDM)**: 원천 표준화부터 매칭•병합, 골든 레코드 저장, 교차 매핑, 스튜어드 검토를 연결한 체계이다.
- **원천 어댑터•표준화**: 각 시스템의 로컬 키와 속성을 수집하고 형식•코드를 공통 기준으로 변환하는 구성요소이다.
- **생존 규칙•골든 저장소**: 속성별 기준값을 선정하고 그 결과와 출처•판정 이력을 보관하는 구성요소이다.
- **교차 매핑•계층**: 중앙 기준 식별자와 원천 키 및 개체 간 상하 관계를 연결하는 구성요소이다.
- **스튜어드 검토 흐름**: 자동 판정이 모호한 후보를 담당자가 검토해 병합•분리를 승인하는 절차이다.

</details>

#### 한줄 요약

- 여러 장부의 같은 사람을 하나의 기준 신분표에 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **5. 골든 레코드•교차 매핑**: 선정한 기준 속성과 원천별 키를 하나의 기준 식별자에 저장하는 단계이다.
- **1. 원천 레코드•로컬 키**: 출처 시스템의 개체 정보와 해당 시스템에서 사용하는 식별자를 함께 전달하는 단계이다.
- **2. 표준 속성값•차단 키**: 속성 형식을 통일하고 비교할 후보 범위를 줄이는 검색 기준을 만드는 단계이다.
- **3. 후보 기준 식별자**: 기존 매핑과 판정 이력에서 동일 개체일 가능성이 있는 중앙 식별자를 조회하는 단계이다.
- **4. 매칭 근거•모호 후보**: 자동 판정의 근거와 확정하기 어려운 후보를 담당자에게 제공하는 단계이다.

</details>

```mermaid

    participant S as 원천 어댑터
    participant N as 표준화•품질
    participant M as 매칭•병합 엔진
    participant A as 데이터 스튜어드
    participant G as 골든 저장소
    S->>N: 1. 원천 레코드•로컬 키
    N->>M: 2. 표준 속성값•차단 키
    M->>G: 3. 후보 기준 식별자
    G-->>M: 속성•판정 이력 반환
    M->>A: 4. 매칭 근거•모호 후보
    A-->>M: 병합•분리 승인
    M->>G: 5. 골든 레코드•교차 매핑
```

**동작 원리**

1. **원천 레코드•로컬 키**: 출처•변경 시각과 함께 원천 개체를 표준화 단계에 전달
2. **표준 속성값•차단 키**: 코드•주소•형식을 통일하고 비교 후보 집합 축소
3. **후보 기준 식별자**: 원천 매핑과 이전 판정 이력을 기준으로 비교 대상 조회
4. **매칭 근거•모호 후보**: 유사도•생존 규칙의 판정 근거를 스튜어드에게 제공
5. **골든 레코드•교차 매핑**: 생존 속성과 원천별 키를 단일 기준 식별자에 저장

#### 한줄 요약

- 기록 형식을 맞추고 같은 사람 후보를 찾은 뒤 애매한 건을 확인해 기준 신분표와 원래 장부 번호를 연결한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **등록소(Registry)**: 원천 속성은 유지하면서 중앙에서 기준 식별자와 로컬 키 연결만 관리하는 마스터 데이터 관리(Master Data Management, MDM) 방식이다.
- **통합(Consolidation)**: 여러 원천을 중앙 골든 레코드 사본으로 단방향 통합해 분석에 제공하는 방식이다.
- **공존(Coexistence)**: 중앙과 원천 시스템이 기준정보를 양방향으로 공유•동기화하는 방식이다.
- **트랜잭션 허브(Transaction Hub)**: 중앙이 권위 있는 골든 레코드의 생성•변경을 통제하는 방식이다.

</details>

| MDM 구축 방식 | 등록소(Registry) | 통합(Consolidation) | 공존(Coexistence) | 트랜잭션 허브(Transaction Hub) |
|:---|:---|:---|:---|:---|
| 적용 기준 | **원천 영향 최소화** | **분석용 기준 통합** | **기존 시스템 양방향 공유** | **중앙 생성•변경 통제** |
| 핵심 특징 | **식별 링크•교차 매핑** | 단방향 **골든 레코드 사본** | **양방향 동기화** | 권위 있는 **골든 레코드** |
| 한계 | **원천 불일치** 잔존 | 기준정보 **최신성 지연** | **충돌•동기화 복잡도** | **중앙 장애•강한 종속성** |

#### 한줄 요약

- 중앙이 번호만 연결할지, 사본을 모을지, 서로 고칠지, 원본 자체가 될지에 따라 나뉜다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **오병합•과소 병합**: 서로 다른 개체를 합치거나 같은 개체를 나눠 두는 두 가지 매칭 오류이다.
- **차단 키•후보 재현율**: 비교 후보를 제한하는 키와 실제 동일 개체 후보를 빠뜨리지 않고 포함한 비율이다.
- **자동 병합•검토•분리 임계 구간**: 매칭 점수에 따라 자동 병합, 사람 검토, 별도 개체 유지로 나누는 판정 범위이다.
- **권위 원천•유효성 규칙**: 속성별로 우선 신뢰할 출처와 값이 기준을 충족하는지 판단하는 규칙이다.
- **판정 이력•분리•재배포 절차**: 병합 근거를 기록하고 오병합을 되돌린 뒤 정정 정보를 다시 전달하는 복구 절차이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 차단 키가 좁으면 **후보 누락**, 넓으면 비교량 급증 | 다중 **차단 키•후보 재현율** 평가 | 매칭의 **비교 비용•후보 누락** 균형 |
| 매칭 임계값이 부정확하면 **오병합•과소 병합** 증가 | 자동 병합•검토•분리 **임계 구간** 설정 | 병합 오류의 **유형별 통제** |
| 속성별 신뢰 원천이 없으면 **골든 레코드 값** 오판 | 속성별 **권위 원천•유효성 규칙** 명시 | 기준값의 **출처•선정 근거** 확보 |
| 오병합 이력이 없으면 잘못된 기준정보의 **전파 복구** 불가 | **판정 이력•분리•재배포 절차** 수립 | 오병합의 **되돌리기•재동기화** 가능 |

#### 한줄 요약

- 잘못 합친 고객과 놓친 중복 고객, 사람이 확인한 시간까지 함께 재야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **통합(Consolidation)**: 여러 원천을 중앙 골든 레코드로 단방향 통합해 분석에 제공하는 마스터 데이터 관리(Master Data Management, MDM) 방식이다.
- **등록소(Registry)**: 원천 정보는 유지하고 중앙에서 기준 식별자와 로컬 키의 연결만 관리하는 방식이다.
- **공존(Coexistence)**: 중앙 기준정보와 원천 시스템이 변경 사항을 양방향으로 공유하는 방식이다.
- **트랜잭션 허브(Transaction Hub)**: 중앙 시스템이 권위 있는 골든 레코드의 생성과 변경을 통제하는 방식이다.

</details>

- 원천 영향 최소화는 **등록소(Registry)** 선택, 분석 통합은 **통합(Consolidation)** 선택
- 양방향 공유는 **공존(Coexistence)** 선택, 중앙 통제는 **트랜잭션 허브(Transaction Hub)** 선택

#### 한줄 요약

- 기준 신분표가 많다는 것보다 왜 합쳤고 어느 값이 어디서 왔으며 잘못되면 되돌릴 수 있는지가 중요하다.
