## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PCB/TCB 하드웨어 레지스터 상태(Hardware Register State)**: CPU 프로그램 카운터(PC), 스택 포인터(SP), 범용 레지스터 및 CR3 제어 레지스터의 실행 문맥 값.
- **TLB 플러시 및 캐시 무효화(TLB Flush & Cache Invalidation)**: 프로세스 전환 시 페이지 테이블 베이스가 바뀌어 가상-물리 변환 캐시가 초기화되고 메모리 지연이 급증하는 현상.

</details>

- 정의/개념: CPU 코어가 인터럽트/스케줄링에 의해 실행 대상을 교체할 때 **PCB/TCB 하드웨어 레지스터 상태를 백업·복원**하는 커널 제어 기제
- 배경/필요성: 다중 프로그래밍 시 주소 공간 교체(CR3 변경)에 따른 TLB 플러시 및 캐시 무효화 오버헤드 최소화 필요

#### 한줄 요약

- CPU 하나를 여러 프로세스가 교대 사용하기 위해 실행 상태를 PCB/TCB에 저장·복원하는 운영체제 핵심 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CR3 레지스터(Control Register 3, CR3)**: CPU가 페이지 테이블 기준 주소를 저장하는 레지스터로, 프로세스 전환 시 새 프로세스의 주소 공간으로 전환하기 위해 교체되는 MMU 제어 레지스터.
- **TLB 플러시(TLB Flush)**: 프로세스 전환 시 이전 프로세스의 가상-물리 주소 변환 캐시(TLB)를 무효화하는 작업으로, 이후 첫 메모리 접근 시 페이지 테이블 탐색(Page Walk)을 유발.
- **주소 변환 비용(Address Translation Overhead)**: TLB 플러시 이후 TLB 미스 급증으로 발생하는 메모리 접근 지연.

</details>

- CPU 레지스터·PC·SP 및 **CR3** 레지스터를 **PCB/TCB** 대상 저장하여 실행 상태 보존
- 프로세스 간 전환 시 주소 공간 교체로 **TLB 플러시** 발생 및 **주소 변환 비용** 급증
- 동일 프로세스 내 스레드 전환은 주소 공간 유지로 **TLB 플러시** 불필요

#### 한줄 요약

- 프로세스 전환은 TLB 플러시를 수반해 스레드 전환보다 문맥 전환 비용이 크게 증가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 스택(Kernel Stack)**: 인터럽트 발생 시 사용자 모드 레지스터를 즉시 저장하기 위해 프로세스별로 커널 공간에 할당된 전용 스택.

</details>

```text
[ 문맥 전환 구조 ]
커널
├─ 스케줄러 (실행 대상 PCB/TCB 선정)
├─ PCB 저장부
│   ├─ CR3 (페이지 테이블 기준 주소)
│   ├─ 파일 핸들·시그널 상태
│   └─ 스케줄링 우선순위·상태
├─ TCB 저장부
│   ├─ PC (프로그램 카운터)
│   ├─ 레지스터 세트
│   └─ 스택 포인터 (SP)
└─ 커널 스택 (인터럽트 시 즉시 레지스터 덤프)
```

선의 의미: 가지(`├─`, `└─`)는 커널이 문맥 전환 시 보존·복원하는 상태 필드 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 스케줄러 | 런 큐에서 다음 실행 대상 **PCB/TCB** 선정 |
| PCB 저장부 | **CR3**·파일 핸들·스케줄링 상태 보관 |
| TCB 저장부 | **PC·레지스터·SP** 경량 보관 |
| 커널 스택 | 인터럽트 발생 시 레지스터 즉시 저장 공간 제공 |

#### 한줄 요약

- 스케줄러가 PCB/TCB에서 다음 실행 대상을 선정하고 커널 스택에서 상태를 복원

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타이머 인터럽트(Timer Interrupt)**: 하드웨어 타이머가 일정 주기(Time Quantum)마다 발생시키는 인터럽트로, 선점형 스케줄링의 강제 전환 신호.

</details>

```text
실행 중인 프로세스 P1
   │
   ▼
1. 타이머 인터럽트 발생
   │
   ▼
2. P1 상태 저장 (레지스터 → 커널 스택 → PCB/TCB)
   │
   ▼
3. 스케줄러: 다음 PCB/TCB 선정 (P2)
   │
   ├─ 프로세스 전환: CR3 교체 → TLB 플러시
   └─ 스레드 전환: CR3 유지 → TLB 보존
   │
   ▼
4. P2 상태 복원 (PCB/TCB → 레지스터)
   │
   ▼
P2 실행 재개
```

**동작 원리**

1. **타이머 인터럽트 발생**: 할당 시간 만료 시 하드웨어 타이머가 인터럽트를 발생시켜 현재 실행 프로세스를 중단
2. **상태 저장**: CPU 레지스터 값을 커널 스택에 즉시 기록하고 현재 프로세스의 **PCB/TCB** 활용 갱신
3. **스케줄러 실행**: 스케줄러가 런 큐를 검사하여 우선순위 기반으로 다음 실행 대상 **PCB/TCB** 활용 선정
4. **상태 복원**: 선정된 프로세스의 **PCB/TCB**에서 레지스터 값을 복원하여 CPU 실행 재개

#### 한줄 요약

- 인터럽트 발생 시 상태를 저장하고, 스케줄러가 선정한 다음 프로세스의 상태를 복원하여 전환

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 워크(Page Walk)**: TLB 미스 발생 시 CPU가 다단계 페이지 테이블을 순차적으로 탐색하여 물리 주소를 산출하는 과정으로, 수 사이클~수십 사이클 소요.

</details>

| 구분 | 프로세스 전환 (Process Context Switch) | 스레드 전환 (Thread Context Switch) |
|:---|:---|:---|
| 적용 기준 | 독립 주소 공간을 가진 별도 프로세스 간 **CPU 이양** 시 | 동일 프로세스 내 스레드 간 **CPU 이양** 시 |
| 핵심 특징 | **CR3** 교체·**TLB 플러시**·**PCB** 교체 수행 | **TCB** 단독 교체, CR3·TLB 유지 |
| 한계 | **TLB 플러시** 후 **페이지 워크** 급증으로 초기 성능 저하 | 주소 공간 공유로 잘못된 메모리 접근이 전체 프로세스에 영향 |

#### 한줄 요약

- 프로세스 전환은 TLB 플러시로 인한 주소 변환 비용이 크고, 스레드 전환은 경량이지만 메모리 보호 경계 없음

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 친화성(CPU Affinity, CPU Pinning)**: 특정 스레드·프로세스를 지정 CPU 코어에 고정 배치하여 코어 간 이동에 따른 캐시 무효화를 방지하는 기법.
- **비동기 I/O(Asynchronous I/O)**: I/O 대기 중 프로세스를 블록하지 않고 완료 시 콜백으로 통지하는 방식으로, I/O 대기 기인 문맥 전환을 감소시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 빈번한 **문맥 전환** 기반 실제 처리 시간 비율 감소 | 타임 퀀텀 조정으로 전환 빈도 제어 | CPU 가용률 향상 |
| 스레드의 코어 간 이동으로 L1/L2 캐시 반복 무효화 | **CPU 친화성** 기반 스레드를 특정 코어에 고정 | 캐시 재사용률 향상으로 **주소 변환 비용** 감소 |
| I/O 대기 기인 잦은 블록으로 **문맥 전환** 증가 | **비동기 I/O** 적용으로 대기 중 CPU 반환 최소화 | I/O 대기 기인 전환 횟수 감소 |

#### 한줄 요약

- 전환 빈도는 타임 퀀텀으로, 캐시 낭비는 CPU 친화성으로, I/O 블록은 비동기 처리로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **문맥 전환 최적화 기준**: TLB 플러시 비용(프로세스 전환)과 캐시 낭비(코어 이동) 중 우선 병목에 따라 친화성 설정·비동기 I/O를 적용하는 판단 기준.

</details>

- **TLB 플러시** 비용이 병목이면 **스레드 기반** 전환, 코어 캐시 낭비가 병목이면 **CPU 친화성** 적용

#### 한줄 요약

- TLB 비용을 줄이려면 스레드 전환을 우선하고, 캐시 낭비를 줄이려면 CPU 친화성으로 코어를 고정
