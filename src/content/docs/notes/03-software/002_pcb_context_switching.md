## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **문맥 전환(Context Switching)**: CPU가 실행 중인 프로세스/스레드의 레지스터 문맥을 저장하고 새 대상의 문맥을 복원하여 실행을 교체하는 커널 기제.
- **PCB(Process Control Block)**: 프로세스의 가상 주소 공간(CR3), 레지스터, 파일 핸들, 스케줄링 상태를 보관하는 커널 자료구조.

</details>

- 정의/개념: CPU 코어가 스케줄링 시 실행 상태를 교체하기 위해 **PCB/TCB 레지스터 문맥을 저장 및 복원**하는 커널 제어 기제
- 배경/필요성: 다중 프로그래밍 환경에서 **주소 공간 교체에 따른 TLB 플러시 및 캐시 무효화 지연 극복 불가**

#### 한줄 요약
- 인터럽트 발생 시 현재 CPU 상태를 PCB/TCB에 저장하고 새 프로세스 상태를 복원하여 시분할 다중 처리를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CR3 레지스터(Control Register 3)**: CPU가 페이지 테이블 베이스 물리 주소를 가리키는 제어 레지스터로, 프로세스 전환 시 새 주소 공간으로 변경됨.
- **TLB 플러시(TLB Flush)**: 프로세스 전환 시 가상-물리 주소 변환 캐시(TLB)가 무효화되어 이후 첫 메모리 접근 시 페이지 테이블 워크가 발생하는 현상.

</details>

- CPU 범용 레지스터, PC, SP 및 **CR3 레지스터**를 PCB/TCB에 원자적으로 저장 및 복원
- 프로세스 간 전환 시 주소 공간 교체로 **TLB 플러시** 및 캐시 미스 오버헤드 수반
- 동일 프로세스 내 스레드 전환 시 CR3 레지스터 및 TLB 캐시를 보존하여 초고속 전환 달성

#### 한줄 요약
- 프로세스 전환은 TLB 플러시 비용이 수반되며, 스레드 전환은 주소 공간을 공유하여 오버헤드가 적다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 스택(Kernel Stack)**: 인터럽트 발생 시 사용자 모드 레지스터를 즉시 덤프하기 위해 프로세스별로 할당된 전용 커널 메모리 스택.

</details>

```text
[문맥 전환 및 PCB/TCB 제어 구조]
|-- 커널 스케줄러 (런 큐 검사 및 차기 실행 대상 선정)
|-- 프로세스 PCB 저장부
|   |-- CR3 레지스터 (페이지 디렉터리 베이스 주소)
|   |-- 파일 디스크립터 테이블 및 시그널 마스크
|   `-- 스케줄링 우선순위 및 프로세스 상태 (State)
|-- 스레드 TCB 저장부 (PC·SP·범용 레지스터 세트)
`-- 커널 스택 (인터럽트 진입 시 트랩 프레임 즉시 보존)
```

선의 의미: 계층 및 하드웨어 문맥 저장 구조

| 구성요소 | 책임 |
|:---|:---|
| **스케줄러** | 런 큐(Run Queue)에서 스케줄링 정책에 따라 차기 실행 **PCB/TCB** 선정 |
| **PCB 저장부** | 가상 메모리 매핑(**CR3**), 파일 디스크립터, 시그널 상태 등 프로세스 자원 보관 |
| **TCB 저장부** | 프로그램 카운터(PC), 스택 포인터(SP), 범용 레지스터 등 스레드 문맥 보관 |
| **커널 스택** | 사용자 모드에서 커널 모드로 트랩 진입 시 CPU 레지스터를 덤프하는 임시 버퍼 |

#### 한줄 요약
- 스케줄러, PCB/TCB 자료구조, 커널 스택이 유기적으로 결합되어 문맥 전환을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타이머 인터럽트(Timer Interrupt)**: 타임 슬라이스(Time Slice) 만료 시 CPU에 인터럽트를 발생시켜 강제 선점 스케줄링을 트리거하는 하드웨어 신호.

</details>

```text
실행 중인 프로세스 P1에 타이머 인터럽트 발생
        │
   CPU 레지스터 값을 커널 스택 및 P1의 PCB/TCB에 저장
        │
   커널 스케줄러가 다음 실행 대상 P2를 선정
        │
   P1과 P2가 서로 다른 프로세스인가?
   ┌────┴─────┐
  예           아니오 (동일 프로세스 내 스레드)
   │             │
CR3 레지스터 교체  CR3 및 TLB 유지
및 TLB 플러시     (주소 공간 보존)
   │             │
   └────┬────────┘
        │
   P2의 PCB/TCB에서 CPU 레지스터 값 복원
        │
   IRET 명령어로 P2 사용자 모드 실행 재개
```

#### 한줄 요약
- 인터럽트 발생 → 현재 상태 PCB 저장 → 다음 프로세스 선정 → CR3 교체 판정 → 상태 복원 후 재개 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 워크(Page Walk)**: TLB 미스 발생 시 CPU MMU가 4단계 페이지 테이블을 순회하며 물리 주소를 찾는 고비용 메모리 접근 동작.

</details>

| 문맥 전환 유형 | 프로세스 문맥 전환 (Process) | 스레드 문맥 전환 (Thread) | 유저 공간 코루틴 전환 (Coroutine) |
|:---|:---|:---|:---|
| 주소 공간 교체 | **CR3 교체** (MMU 페이지 테이블 변경) | 주소 공간 유지 (동일 CR3) | 주소 공간 유지 (유저 메모리) |
| TLB 플러시 유무 | **TLB 플러시 발생** (페이지 워크 지연) | TLB 유지 (캐시 적중률 유지) | TLB 유지 (커널 개입 없음) |
| 문맥 전환 오버헤드 | 수 마이크로초 ($\mu s$, 고비용) | 수백 나노초 ($ns$, 중간 비용) | 수십 나노초 ($ns$, 초저비용) |
| 커널 모드 개입 | 커널 인터럽트 핸들러 필수 | 커널 스케줄러 필수 | 사용자 런타임 자체 스케줄링 |

#### 한줄 요약
- 프로세스 전환은 TLB 플러시 비용이 크고, 스레드 전환은 중간이며, 코루틴은 커널 없이 초고속 전환된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 친화성(CPU Affinity)**: 특정 프로세스/스레드를 지정된 CPU 코어에 고정 바인딩하여 코어 이동에 따른 L1/L2 캐시 무효화를 방지하는 기법.
- **PCID(Process-Context Identifier)**: 프로세스 전환 시 TLB에 태그를 붙여 CR3 교체 후에도 타 프로세스의 유효 TLB를 플러시하지 않는 CPU 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 문맥 전환으로 인한 CPU 유효 처리율 감소 | 타임 슬라이스(Time Slice) 적응형 튜닝 및 스레드 풀 적용 | 불필요한 선점 횟수 감소 및 CPU 순수 연산 효율 향상 |
| 코어 간 스레드 이동으로 L1/L2 캐시 콜드 미스 | **CPU 친화성(CPU Affinity/Pinning)** 바인딩 적용 | L1/L2 캐시 적중률 극대화 및 메모리 대역폭 절감 |
| 프로세스 전환 시 TLB 플러시로 인한 지연 | CPU 하드웨어 **PCID(Process-Context Identifier)** 활성화 | CR3 교체 시 TLB 엔트리 보존 및 페이지 워크 80% 감소 |
| 블로킹 I/O 대기로 인한 문맥 전환 빈발 | epoll/io_uring 기반 **비동기 논블로킹 I/O** 전환 | I/O 대기 문맥 전환 원천 제거 및 대규모 동시성 수용 |

#### 한줄 요약
- 타임 슬라이스 최적화, CPU Affinity 코어 고정, PCID 하드웨어 태깅, 비동기 I/O로 문맥 전환 지연을 최소화한다.

## Ⅶ. 결론

- 고성능 시스템 설계 시 **스레드 풀 기반 스레드 전환**을 우선하고, **CPU Affinity 및 PCID 하드웨어 가속**을 결합하여 문맥 전환 오버헤드 극소화 달성

#### 한줄 요약
- 문맥 전환은 시분할 운영체제의 핵심 기제이며, TLB 및 CPU 캐시 보존 최적화가 전체 시스템 성능을 좌우한다.
