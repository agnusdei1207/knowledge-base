## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **문맥 전환(Context Switching)**: CPU가 실행 중인 프로세스/스레드의 레지스터 문맥을 저장하고 새 대상의 문맥을 복원하여 실행을 교체하는 커널 기제.
- **PCB(Process Control Block)**: 프로세스의 가상 주소 공간(CR3), 레지스터, 파일 핸들, 스케줄링 상태를 보관하는 커널 자료구조.

</details>

- 정의/개념: 스케줄링 시 실행 문맥을 **PCB**/TCB에 저장·복원하는 커널의 **문맥 전환** 제어 기제
- 배경/필요성: 단일 코어에서 다중 프로세스를 시분할하려면 중단 시점의 레지스터·PC·SP·MMU 상태를 어딘가에 보존해야 하므로, 커널 메모리의 PCB/TCB를 문맥 저장소로 두어 전환 비용을 저장·복원 1회로 한정

#### 한줄 요약
- 인터럽트 발생 시 현재 CPU 상태를 PCB/TCB에 저장하고 새 프로세스 상태를 복원하여 시분할 다중 처리를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CR3 레지스터(Control Register 3)**: CPU가 페이지 테이블 베이스 물리 주소를 가리키는 제어 레지스터로, 프로세스 전환 시 새 주소 공간으로 변경됨.
- **TLB 플러시(TLB Flush)**: 프로세스 전환 시 가상-물리 주소 변환 캐시(TLB)가 무효화되어 이후 첫 메모리 접근 시 페이지 테이블 워크가 발생하는 현상.

</details>

- CPU 레지스터·PC·SP와 **CR3 레지스터** 저장·복원
- 프로세스 간 전환 시 주소 공간 교체로 **TLB 플러시** 및 캐시 미스 오버헤드 수반
- 동일 프로세스의 스레드 전환은 **CR3 레지스터**와 TLB를 유지해 비용 절감

#### 한줄 요약
- 프로세스 전환은 TLB 플러시 비용이 수반되며, 스레드 전환은 주소 공간을 공유하여 오버헤드가 적다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 스택(Kernel Stack)**: 인터럽트 발생 시 사용자 모드 레지스터를 즉시 덤프하기 위해 프로세스별로 할당된 전용 커널 메모리 스택.

</details>

```text
[문맥 전환 및 PCB/TCB 제어 구조]
|-- 커널 스케줄러 (런 큐 검사 및 차기 실행 대상 선정)
|-- 프로세스 PCB 저장부
|   |-- CR3 레지스터 (페이지 디렉터리 베이스 주소)
|   |-- 파일 디스크립터 테이블 및 시그널 마스크
|   `-- 스케줄링 우선순위 및 프로세스 상태 (State)
|-- 스레드 TCB 저장부 (PC·SP·범용 레지스터 세트)
`-- 커널 스택 (인터럽트 진입 시 트랩 프레임 즉시 보존)
```

선의 의미: 계층 및 하드웨어 문맥 저장 구조

| 구성요소 | 책임 |
|:---|:---|
| 스케줄러 | 런 큐에서 차기 실행 PCB/TCB 선정 |
| PCB 저장부 | **CR3**·파일 디스크립터·프로세스 상태 보관 |
| TCB 저장부 | PC·SP·범용 레지스터 등 스레드 문맥 보관 |
| 커널 스택 | 트랩 진입 시 CPU 레지스터 임시 보관 |

#### 한줄 요약
- 문맥이 CPU 레지스터가 아니라 커널 메모리의 PCB에 놓이기 때문에 전환이 가능해지며, 그 대가로 저장·복원 구간이 아무 일도 하지 못하는 순수 오버헤드로 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타이머 인터럽트(Timer Interrupt)**: 타임 슬라이스(Time Slice) 만료 시 CPU에 인터럽트를 발생시켜 강제 선점 스케줄링을 트리거하는 하드웨어 신호.

</details>

```text
실행 중인 프로세스 P1에 타이머 인터럽트 발생
        │
   CPU 레지스터 값을 커널 스택 및 P1의 PCB/TCB에 저장
        │
   커널 스케줄러가 다음 실행 대상 P2를 선정
        │
   P1과 P2가 서로 다른 프로세스인가?
   ┌────┴─────┐
  예           아니오 (동일 프로세스 내 스레드)
   │             │
CR3 레지스터 교체  CR3 및 TLB 유지
및 TLB 플러시     (주소 공간 보존)
   │             │
   └────┬────────┘
        │
   P2의 PCB/TCB에서 CPU 레지스터 값 복원
        │
   IRET 명령어로 P2 사용자 모드 실행 재개
```

분기 결과: **타이머 인터럽트**로 진입해 **커널 스택**에 트랩 프레임을 저장하는 비용은 두 경로가 같고, 다른 프로세스로 넘어갈 때만 CR3 교체와 TLB 플러시가 추가된다.

#### 한줄 요약
- 전환 비용을 실제로 만드는 지점은 레지스터 저장이 아니라 주소 공간이 바뀌는 CR3 교체이므로, 같은 프로세스 안의 스레드 전환은 그 단계를 건너뛰어 훨씬 싸게 끝난다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 워크(Page Walk)**: TLB 미스 발생 시 CPU MMU가 4단계 페이지 테이블을 순회하며 물리 주소를 찾는 고비용 메모리 접근 동작.

</details>

| 문맥 전환 유형 | 프로세스 | 스레드 | 사용자 공간 코루틴 |
|:---|:---|:---|:---|
| 적용 기준 | 강한 결함 격리 요구 | 공유 주소 공간의 병렬 실행 | 대규모 동시 I/O 작업 |
| 핵심 특징 | CR3 교체로 주소 공간 전환 | 동일 CR3에서 TCB 문맥 교체 | 사용자 런타임의 협력적 스케줄링 |
| 한계 | **TLB 플러시**·IPC 비용 | 데이터 경쟁·장애 전파 | 블로킹 작업의 런타임 정지 |

#### 한줄 요약
- 프로세스는 주소 공간, 스레드는 레지스터, 코루틴은 런타임 문맥을 바꾼다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 친화성(CPU Affinity)**: 특정 프로세스/스레드를 지정된 CPU 코어에 고정 바인딩하여 코어 이동에 따른 L1/L2 캐시 무효화를 방지하는 기법.
- **PCID(Process-Context Identifier)**: 프로세스 전환 시 TLB에 태그를 붙여 CR3 교체 후에도 타 프로세스의 유효 TLB를 플러시하지 않는 CPU 기능.
- **타임 슬라이스(Time Slice)**: 스케줄러가 한 프로세스에 연속 배정하는 CPU 시간 조각으로, 길이를 늘리면 선점 횟수가 줄고 짧게 하면 응답성이 오르는 조정 변수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 선점으로 CPU 유효 처리율 감소 | **타임 슬라이스** 조정·스레드 풀 적용 | 선점 횟수 감소·연산 비율 증가 |
| 코어 이동으로 L1/L2 캐시 미스 | **CPU 친화성** 바인딩 적용 | 캐시 적중률 증가·메모리 대역폭 절감 |
| 프로세스 전환의 **TLB 플러시 지연** | 하드웨어 **PCID** 활성화 | TLB 엔트리 보존·**페이지 워크** 감소 |
| 블로킹 I/O로 문맥 전환 빈발 | 비동기 논블로킹 I/O 전환 | 대기 전환 감소·동시성 확대 |

#### 한줄 요약
- 문맥 전환 비용은 없앨 수 없고 옮길 수만 있으므로, 타임 슬라이스를 늘려 전환 횟수를 줄일지 CPU 친화성·PCID로 전환 1회의 캐시·TLB 손실을 줄일지를 워크로드 성격으로 결정한다.

## Ⅶ. 결론

- 현대 시분할 멀티태스킹 운영체제의 핵심 스케줄링 제어 메커니즘으로 확립되었으며, 실무 고성능 시스템 설계에서는 문맥 전환 오버헤드를 최소화하기 위해 하드웨어 PCID(Process-Context Identifier) 활성화, 코어 간 캐시 웜 상태를 유지하는 CPU Affinity(친화성) 고정 및 Non-blocking 비동기 I/O(epoll/io_uring)를 결합하여 처리량을 극대화

#### 한줄 요약
- 주소 공간 전환에는 PCID를 쓰고 코어 이동이 잦으면 CPU 친화성을 적용한다.
