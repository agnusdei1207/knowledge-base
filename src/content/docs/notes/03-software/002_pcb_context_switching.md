## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **컨텍스트 스위칭(Context Switching)**: 현재 실행 문맥을 저장하고 다음 문맥을 복원해 실행 주체를 교체하는 운영체제 기법이다.
- **프로세스 제어 블록(Process Control Block, PCB)**: 프로세스 상태•주소 공간•자원 참조를 저장하는 운영체제 자료구조이다.
- **스레드 제어 블록(Thread Control Block, TCB)**: 스레드별 레지스터•스택 포인터•스케줄 상태를 저장하는 자료구조이다.
- **실행 문맥(Execution Context)**: 중단 지점부터 실행을 재개하는 데 필요한 프로그램 카운터•레지스터•스택 포인터 상태이다.

</details>
- 정의/개념: **PCB**와 **TCB**에 **실행 문맥**을 저장•복원해 실행 주체를 교체하는 **컨텍스트 스위칭** 기법이다.
- 배경/필요성: 문맥을 저장하지 않으면 선점된 작업의 중단 지점으로 복귀할 수 없다.

#### 한줄 요약

- 현재 문맥 저장과 다음 문맥 복원으로 실행 주체를 교체한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 가상 주소의 물리 주소 변환 결과를 저장하는 캐시이다.
- **캐시 지역성(Cache Locality)**: 최근 사용한 코드•데이터가 프로세서 캐시에 남아 재사용되는 성질이다.
- **PCB 문맥 보존**: 프로세스 상태와 자원 참조를 저장하는 처리이다.
- **TCB 문맥 보존**: 스레드 레지스터와 스택 포인터를 저장하는 처리이다.

</details>

- **PCB 문맥 보존**과 **TCB 문맥 보존**으로 선점 전 실행 지점을 복구한다.
- **TLB**와 **캐시 지역성** 손실로 전환 비용이 증가한다.

#### 한줄 요약

- 응답성 향상과 문맥 전환 비용 사이에는 상충 관계가 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 현재 스레드의 프로그램 카운터와 레지스터 문맥을 실행하는 구성이다.
- **운영체제 커널(Operating System Kernel)**: 문맥 저장•복원과 실행 제어를 수행하는 구성이다.
- **스케줄러(Scheduler)**: 실행 가능 주체 중 다음 실행 대상을 선택하는 구성이다.
- **PCB 저장부(PCB Storage)**: 프로세스 주소 공간•상태•자원 참조를 보관하는 구성이다.
- **TCB 저장부(TCB Storage)**: 스레드 레지스터•스택•스케줄 상태를 보관하는 구성이다.

</details>

```text
[CPU]
  |
  |
+----------------------- [운영체제 커널] -----------------------+
|                              |                                |
|                        [스케줄러]                             |
|                         /        \                            |
|                        /          \                           |
|                 [PCB 저장부]   [TCB 저장부]                  |
+---------------------------------------------------------------+
```

선의 의미: CPU와 커널 경계 안 스케줄러의 선은 실행 제어 관계, 스케줄러에서 PCB와 TCB로 갈라지는 선은 다음 실행 주체를 고를 때 프로세스 자원 정보와 스레드 실행 문맥을 함께 참조하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| CPU | 현재 문맥 실행 |
| 운영체제 커널 | 문맥 저장•복원 |
| 스케줄러 | 다음 실행 대상 선택 |
| PCB 저장부 | 주소 공간•자원 관리 |
| TCB 저장부 | 스레드 문맥 보관 |

#### 한줄 요약

- **운영체제 커널**, **스케줄러**, **PCB 저장부**, **TCB 저장부** 기반 문맥 전환 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **선점(Preemption)**: 할당 시간 종료나 높은 우선순위 작업 도착 시 실행 중인 CPU를 회수하는 동작이다.
- **런 큐(Run Queue)**: CPU 실행을 기다리는 준비 상태 스레드 목록이다.
- **프로세서 친화도(Processor Affinity)**: 스레드가 실행될 수 있는 프로세서 범위를 제한하는 정책이다.
- **페이지 테이블(Page Table)**: 가상 주소와 물리 주소의 대응 정보를 저장한 표이다.
- **프로그램 카운터(Program Counter, PC)**: 다음에 실행할 명령어의 주소를 저장하는 레지스터이다.
- **선점 인터럽트(Preemption Interrupt)**: 실행 시간을 회수해 커널의 스케줄링을 시작하게 하는 하드웨어•타이머 신호이다.
- **현재 실행 문맥 저장**: 프로그램 카운터와 레지스터를 현재 TCB에 보존하는 단계이다.
- **런 큐 정책 평가**: 우선순위와 친화도 및 준비 상태를 확인하는 단계이다.
- **다음 PCB·TCB 선택**: 다음 실행 주체와 저장 문맥을 확정하는 단계이다.
- **주소 공간 전환**: 다른 프로세스의 페이지 테이블로 변환 상태를 바꾸는 단계이다.
- **문맥 복원·디스패치**: 레지스터와 스택을 복원하고 CPU 제어권을 넘기는 단계이다.

</details>

```text
[선점 인터럽트•대기 발생]
            │
            ▼
1. 현재 실행 문맥 저장
            │
            ▼
2. 런 큐 정책 평가
            │
            ▼
3. 다음 PCB•TCB 선택
            │
      ┌─────┴──────────┐
      │ 동일 프로세스 │ 다른 프로세스
      │                ▼
      │        4. 주소 공간 전환
      └────────┬───────┘
               ▼
5. 문맥 복원•디스패치
               │
               ▼
        [CPU 실행 재개]
```

### 동작 원리

1. **현재 실행 문맥 저장**: 프로그램 카운터•레지스터를 현재 TCB에 보존한다.
2. **런 큐 정책 평가**: 우선순위•친화도•준비 상태를 확인한다.
3. **다음 PCB•TCB 선택**: 실행 주체와 저장 문맥을 확정한다.
4. **주소 공간 전환**: 다른 프로세스면 페이지 테이블을 교체한다.
5. **문맥 복원•디스패치**: 레지스터•스택 복원 후 제어권을 이전한다.

#### 한줄 요약

- **현재 실행 문맥 저장**, **런 큐 정책 평가**, **다음 PCB·TCB 선택**, **주소 공간 전환**, **문맥 복원·디스패치**를 순서대로 수행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **주소 공간 전환(Address-space Switch)**: 다음 프로세스의 페이지 테이블에 맞춰 가상 주소 변환 상태를 바꾸는 동작이다.
- **디스패치(Dispatch)**: 스케줄러가 고른 실행 주체에 CPU 제어권을 넘기는 동작이다.
- **지역성 손실(Locality Loss)**: 전환 뒤 기존 캐시•TLB 내용의 재사용률이 낮아져 재적재 비용이 발생하는 현상이다.

</details>

| 전환 범위 | 프로세스 전환 | 동일 프로세스 스레드 전환 |
|:---|:---|:---|
| 적용 기준 | 다른 프로세스 **디스패치** | 동일 프로세스 내 스레드 교체 |
| 핵심 특징 | PCB•TCB•**주소 공간 전환** | TCB의 실행 문맥 전환 |
| 한계 | TLB•캐시 **지역성 손실** | 공유 캐시 교란 가능성 |

> 요약: 프로세스는 주소 공간까지, 스레드는 실행 문맥만을 전환한다.

#### 한줄 요약

- 프로세스는 주소 공간까지, 스레드는 실행 문맥만 전환한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **시간 할당량(Time Quantum)**: 선점 전 연속 실행을 허용하는 시간이다.
- **꼬리 지연(Tail Latency)**: 지연 분포의 상위 백분위에 해당하는 느린 전환 지연이다.
- **백분위(Percentile)**: 측정값을 작은 순서로 놓았을 때 특정 비율이 그 이하인 경계값이다.
- **보호 구간(Critical Section)**: 공유 커널 상태의 일관성을 위해 한 실행 주체만 진입하도록 제한한 코드 범위이다.
- **최악 실행시간(Worst-Case Execution Time, WCET)**: 특정 코드 경로가 완료되는 데 걸릴 수 있는 최대 시간이다.
- **런 큐 길이(Run-queue Length)**: CPU 실행을 기다리는 준비 상태 작업의 수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **시간 할당량**이 짧아 문맥 전환 비중 급증 | 응답 목표와 전환 시간으로 시간 할당량 조정 | 응답 지연•CPU 효율 균형 |
| 프로세서 이동으로 캐시•TLB **지역성 손실** | **프로세서 친화도**와 부하 분산 공동 적용 | 캐시 재적재 비용 감소 |
| 평균 전환 지연만 보면 **꼬리 지연** 누락 | **백분위** 전환 지연과 **런 큐 길이** 계측 | 간헐적 지연 원인 식별 |
| 긴 **보호 구간**으로 선점•스케줄링 지연 | 보호 구간 축소와 **WCET** 점검 | 응답시간 예측성 향상 |

#### 한줄 요약

- 응답 목표와 **전환 비중**을 함께 반영해 **시간 할당량**을 조정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **전환 비중**: 전체 CPU 시간 중 문맥 저장•복원에 소비한 시간의 비율이다.
- **시간 할당량 조정 기준**: 응답 지연과 전환 비중을 비교해 선점 주기를 늘리거나 줄이는 기준이다.

</details>

- **시간 할당량 조정 기준**에 따라 응답 지연이 목표를 넘으면 할당량을 줄이고, **전환 비중**이 높으면 할당량을 늘린다.

#### 한줄 요약

- 응답 지연과 **전환 비중**에 따라 시간 할당량을 조정한다.
