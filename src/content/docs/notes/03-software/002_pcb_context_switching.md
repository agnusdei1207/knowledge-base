## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **문맥 전환(Context Switching)**: CPU가 하던 일을 멈추고 딴 놈한테 넘길 때, 지금 어디까지 했는지 메모해 두고 다음 놈의 작업 파일을 꺼내오는 교대 작업이다.
- **프로세스 제어 블록(Process Control Block, PCB)**: 프로세스마다 "얘는 누구고, 메모리는 어딨고, 상태는 어떤지" 커널이 꼼꼼히 적어둔 무거운 상태 장부이다.
- **스레드 제어 블록(Thread Control Block, TCB)**: 스레드마다 "얘가 지금 어느 코드를 돌리고 있고, 레지스터 상태는 어떤지" 짧게 적어둔 가벼운 미니 장부이다.

</details>

- 정의: 멀티태스킹 환경에서 CPU 하드웨어 자원을 선점 공유하기 위해 실행 주체의 상태(레지스터, 가상 메모리 등)를 PCB/TCB에 보존하고 신규 문맥을 복원하는 **문맥 전환(Context Switching)**
- 배경: CPU는 하나인데 프로세스는 여러 개라서, 실행 상태 보존 없이는 나중에 자기 차례가 왔을 때 **중단 지점 복귀**가 아예 불가능하기 때문

#### 한줄 요약

- CPU 하나를 여러 명이 나눠 쓰려고 하던 일(문맥)을 장부(PCB/TCB)에 적어놓고 교대하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CR3 레지스터(Control Register 3, CR3)**: CPU가 메모리 지도를 찾을 때 쳐다보는 이정표로, 이게 바뀌면 완전 딴 프로세스 동네로 넘어갔다는 뜻이다.
- **주소 변환 비용(Address Translation Overhead)**: 이정표(CR3)가 바뀔 때마다 기존에 머릿속에 외워둔 지도(TLB)를 다 까먹고 처음부터 다시 길을 찾아야 해서 생기는 딜레이이다.
- **TLB 플러시(TLB Flush)**: 프로세스가 바뀔 때, 예전 프로세스가 쓰던 메모리 단축키 캐시를 싹 다 날려버리는 무자비한 초기화 작업이다.
- **비동기 I/O(Asynchronous I/O)**: 디스크 읽기를 시켜놓고 멍때리며 차례를 넘기는 대신, "다 되면 알려줘" 하고 딴일 하면서 문맥 전환 낭비를 막는 효율적인 통신 방식이다.

</details>

- CPU 레지스터, PC, SP 및 MMU 레지스터(**CR3**)를 커널 메모리(**PCB/TCB**)에 안전하게 덤프해 보존함.
- 프로세스 간 교대 시 주소 공간이 통째로 바뀌면서 **TLB 플러시**가 터지고 메모리 단축키 캐시가 날아감.
- 반면 같은 프로세스 안에서 스레드끼리 교대하면, 주소 지도가 그대로라 **주소 변환 비용**이 획기적으로 줄어듦.

#### 한줄 요약

- 하던 일을 커널에 백업해 두고 교대하는데, 동네(주소 공간)가 바뀌면 뇌를 씻어내야 해서 엄청난 비용이 든다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 스택(Kernel Stack)**: 프로세스가 유저 모드에서 놀다가 인터럽트를 맞고 커널 모드로 끌려올 때, 쓰던 레지스터 값들을 냅다 던져놓는 커널 전용 바구니이다.

</details>

```text
[ 문맥 전환 십자포화 아키텍처 프레임워크 ]
   [ CPU 레지스터 (뇌 상태) ]
          │ (교대 타이머 터짐)
          ▼
┌──── [ 운영체제 커널 ] ────┐
│       [ 스케줄러 ]        │
│        /        \         │
│   [ PCB ]      [ TCB ]    │
│        \        /         │
│      [ 커널 스택 ]        │
└───────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **CPU 레지스터** | 지금 당장 CPU가 멱살 잡고 돌리고 있는 프로세스의 현재 뇌 상태 값들 보존 |
| 커널 스케줄러 | 타이머가 터지면 "시간 다 됐어 나와!" 하고 다음 타자를 **PCB/TCB**에서 골라내는 통제관 |
| **PCB** 저장부 | 가상 메모리 테이블(**CR3**), 열어둔 파일, 프로세스 상태(Ready/Block)를 쑤셔 넣는 창고 |
| **TCB** 저장부 | 스레드 전용 스택 포인터(SP)와 레지스터만 가볍게 떼어서 보관하는 미니 창고 |
| **커널 스택** | 인터럽트 맞는 즉시 프로세스의 하드웨어 레지스터 찌꺼기를 조용히 덤프 기록하는 피난처 |

#### 한줄 요약

- CPU 레지스터에서 뽑아낸 상태 값들을 스케줄러가 받아서 장부(PCB/TCB)와 커널 스택에 욱여넣는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타이머 인터럽트(Timer Interrupt)**: 1밀리초마다 "시간 다 됐다 교대해라!" 하고 CPU를 강제로 멈춰 세우는 매정한 하드웨어 알람이다.

</details>

```text
[ 문맥 전환 상태 보존 및 복원 흐름 ]
                                 │
                                 ▼
         [ 1. 강제 정지: 타이머 인터럽트 터지며 CPU 멈춤 ]
                                 │
                                 ▼
      [ 2. 뇌 상태 보존: 현재 레지스터 값을 커널 스택에 냅다 덤프 ]
                                 │
                                 ▼
      [ 3. 다음 타자 선정: 스케줄러가 런 큐 뒤져서 다음 PCB/TCB 뽑음 ]
                                 │
                 ┌───────────────┴───────────────┐
           ( 다른 프로세스일 때 )              ( 같은 프로세스 스레드일 때 )
                 ▼                               ▼
     [ 4. 뇌 리셋: CR3 갈아끼우고 ]             [ 칭찬 후 4단계 스킵 ]
     [ TLB 싹 날리는 주소 공간 전환 ]
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
      [ 5. 상태 복원: 새 타자 레지스터 꺼내서 CPU에 꽂고 재개 ]
```

### 동작 원리

1. 강제 정지: **타이머 인터럽트**나 I/O 대기가 터지면서 하던 일을 강제로 멈춤.
2. 뇌 상태 보존: CPU 레지스터에 남아있던 값들을 현재 **TCB/PCB**와 **커널 스택**에 덤프해 보존함.
3. 다음 타자 선정: OS 커널 스케줄러가 런 큐(Run-Queue)를 뒤져서 다음 우선순위 프로세스를 뽑아냄.
4. 뇌 리셋(주소 전환): 프로세스가 바뀌면 **CR3** 레지스터를 갈아끼우고 **TLB 플러시**를 때려서 뇌를 씻어냄.
5. 상태 복원: 새로 뽑힌 타자의 레지스터 세트를 CPU에 다시 꽂아 넣고 하던 일 마저 시킴.

#### 한줄 요약

- 알람이 울리면 멈추고 뇌를 백업한 뒤, 다른 프로세스로 넘어가면 기억(TLB)을 다 지우고 새놈의 뇌를 복원한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 프로세스 교대 (Process Context Switch) | 스레드 교대 (Thread Context Switch) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 완전히 남남인 크롬 탭 1번과 2번 사이를 왔다 갔다 할 때 | 크롬 탭 하나 안에서 화면 렌더링 스레드랑 통신 스레드가 교대할 때 |
| 뇌 리셋(MMU 전환) 여부 | 동네가 바뀌었으니 **CR3** 레지스터를 통째로 갈아치움 | 같은 동네라 메모리 지도(CR3)는 그냥 놔두고 옷만 갈아입음 |
| **TLB** 타격 체감 | 기존에 쓰던 메모리 단축키(TLB)가 다 날아가서 지연 시간 폭발함 | 지도를 그대로 쓰니까 단축키도 유지돼서 지연 시간이 거의 없음 |

#### 한줄 요약

- 프로세스 교대는 지도를 다시 펴야 해서 엄청 느리고, 스레드 교대는 지도 펴놓은 채 몸만 바꾸니까 빠르다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **시피유 핀닝(CPU Pinning / Affinity)**: 스레드가 코어 1번, 코어 2번으로 자꾸 메뚜기 뛰면 캐시가 다 날아가니까 "넌 1번 코어에만 박혀 있어!" 하고 멱살 잡고 묶어두는 꼼수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 일은 안 하고 교대만 미친 듯이 하느라 **Context Switch** 딜레이에 CPU가 질식해 죽어감 | 교대 알람 시간(Time Quantum)을 늘려서 한 놈이 진득하게 일하게 튜닝함 | 쓸데없는 교대 비용을 줄이고 실제 일하는 시간(가용률) 극대화 |
| 스레드가 1번 코어 쓰다 2번 코어로 자꾸 이사 다녀서 캐시가 텅텅 비어버리는 재앙 | **시피유 핀닝(Affinity)** 먹여서 한 놈은 무조건 한 코어에서만 놀게 묶어버림 | L1/L2 캐시에 데워둔 데이터가 안 날아가서 성능 개떡상 |
| 디스크 읽느라 프로세스가 자꾸 멈추면서 교대 비용이 눈덩이처럼 불어남 | 대기 타지 말고 **비동기 I/O** 돌려서 안 멈추고 계속 일하게 만듦 | 하릴없이 교대당하는 횟수를 줄여서 주소 변환 낭비 원천 차단 |

#### 한줄 요약

- 교대 빈도를 줄여 시간을 확보하고, 코어 메뚜기를 뛰지 못하게 묶으며, 비동기 처리를 떡칠해 멈춤을 방지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **컨텍스트 스위칭 선택 기준(Context Switching Optimization Criteria)**: 이 시스템이 무겁게 자주 교대해도 버틸 수 있는지, 아니면 교대를 최소한으로 억제해야 하는지 판을 짜는 설계 잣대이다.

</details>

- **컨텍스트 스위칭 선택 기준** 원칙에 따라, 잦은 교대로 캐시가 털리면 **시피유 핀닝**을 걸고, 멍때리는 시간을 줄이려면 **비동기 I/O** 채택 기조 확립함

#### 한줄 요약

- 잦은 문맥 전환은 시스템을 죽이므로 알람 주기를 튜닝하고 프로세스를 코어에 박아버려야 한다.
