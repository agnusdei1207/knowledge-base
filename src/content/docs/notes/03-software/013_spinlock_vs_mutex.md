## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스핀락(Spinlock)**: 화장실 문이 잠겼을 때 딴짓 안 하고 문고리만 미친 듯이 덜컥거리며 열릴 때까지 무한 대기하는(CPU를 갉아먹는) 바쁜 대기(Busy Waiting) 락이다.
- **뮤텍스(Mutex)**: 화장실 문이 잠기면 번호표 뽑고 벤치(대기 큐)에서 쿨쿨 자다가(Sleep), 문 열리면 OS가 깨워줄 때까지 CPU를 남한테 양보하는 점잖은 락이다.
- **적응형 뮤텍스(Adaptive Mutex)**: 화장실에 있는 놈이 볼일 중이면(다른 코어에서 실행 중) 잠깐 스핀락 돌면서 기다려보고, 자고 있으면 자기도 뮤텍스처럼 자버리는 눈치 빠른 혼종 락이다.

</details>

- 정의: 공유 자원을 얻지 못했을 때 기다리는 방식에 따라, CPU를 태우며 대기하는 **스핀락**과 벤치에서 잠들어버리는 **뮤텍스**로 나뉘는 동기화 기법
- 배경: 무조건 큐에 재워버리면 화장실에 잠깐 들어갔다 나오는 경우엔 오히려 눕고 일어나는 **문맥 전환(Context Switch) 비용**이 더 커서 배보다 배꼽이 커지기 때문

#### 한줄 요약

- 락을 기다릴 때 밖에서 발을 동동 구를지(스핀락), 아니면 소파에 누워 한숨 잘지(뮤텍스) 결정하는 것이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바쁜 대기(Busy Waiting)**: `while(locked)` 루프를 미친 듯이 돌리면서 "열렸어? 열렸어?" 하고 CPU 사이클을 쓰레기통에 처박는 무식한 대기 방식이다.
- **문맥 전환 임계점(Context Switch Threshold)**: 스레드를 재우고 깨우는 데 걸리는 오버헤드 시간으로, 이 시간보다 락을 쥐고 있는 시간이 짧으면 무조건 스핀락이 이득이다.

</details>

- 락을 얻을 때까지 CPU를 안 놓고 미친 듯이 뺑뺑이를 도는 **스핀락(Busy Waiting)** 방식.
- 쿨하게 락을 포기하고 OS 커널 대기 큐로 들어가서 꿀잠을 자는 **뮤텍스(Sleep/Block)** 방식.
- 임계 구역의 실행 시간이 **문맥 전환 임계점**보다 기냐 짧으냐에 따라 승패가 갈림.

#### 한줄 요약

- 눕고 일어나는 시간(문맥 전환)보다 빨리 끝날 일이면 스핀락, 오래 걸릴 일이면 뮤텍스가 효율적이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **테스트 앤 세트(Atomic Test-and-Set, TAS)**: 락이 풀려있는지 확인하고 내가 잠그는 2단계 행동을, 중간에 누구도 못 끼어들게 하드웨어 차원에서 딱 한 큐에 끝내버리는 무적의 원자적 명령어이다.

</details>

```text
[ 락 획득 대기 십자포화 아키텍처 ]
            [ 경쟁 스레드 ]
         (TAS 명령어로 찔러봄)
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
  [ 락 획득 성공 ]     [ 락 획득 실패 ]
        │                   │
        ▼                   ▼
  [ 임계 구역 ]     [ 대기 방식 분기 ]
                  (스핀락: 루프 뺑뺑이)
                  (뮤텍스: 수면 블록)
```

| 구성요소 | 책임 |
|:---|:---|
| **테스트 앤 세트(TAS)** | 락 변수를 읽고 쓰는 걸 중간에 새치기 못 하게 하드웨어 단에서 한 방에 처리하는 명령어 |
| 스핀 루프 (Spin Loop) | **스핀락** 쓸 때, CPU 멱살을 잡고 `while` 문을 무한으로 돌려 대는 바쁜 대기실 |
| 커널 대기 큐 | **뮤텍스** 쓸 때, 락 못 얻은 놈을 벤치에 눕혀서 OS가 관리해 주는 수면실 |
| 임계 구역 | 락을 쟁취한 단 한 놈만이 들어가서 코드를 실행하는 1평짜리 독방 |

#### 한줄 요약

- TAS로 찔러보고 실패하면, 스핀락은 루프를 돌고 뮤텍스는 커널 큐에 누워서 잔다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수면 불가 문맥(Non-Sleepable Context)**: 하드웨어 인터럽트(ISR) 처리 중처럼, 절대 잠들면 안 되고 무조건 끝을 봐야 하는 초특급 위급 런타임 상황이다.

</details>

```text
[ 락 대기 방식 선택 십자포화 흐름 ]
┌─────────────────────────────┐
│ 1. 자면 안 되는 상황인가?   │
│ (인터럽트 등 수면 불가 문맥) │
└──────────────┬──────────────┘
               ├─ Yes ─▶ [ 무조건 스핀락 ]
               │ No (자도 됨)
               ▼
┌─────────────────────────────┐
│ 2. 임계 구역 작업 시간 예측 │
│ (금방 끝나냐 오래 걸리냐)   │
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐
│ 3. 문맥 전환 비용과 비교    │
│ (눕고 일어나는 시간 vs 대기) │
└──────────────┬──────────────┘
               ├─ 대기가 더 짧음 ─▶ [ 스핀락 ]
               └─ 대기가 더 김   ─▶ [ 뮤텍스 ]
```

### 동작 원리

1. 수면 가능성 검사: 지금 인터럽트(ISR) 도는 중이면 절대 자면 안 되니까 강제로 **스핀락**을 씀.
2. 시간 예측: 임계 구역 코드가 몇 줄 안 되는지, 아니면 I/O가 떡칠 돼서 오지게 오래 걸릴지 각을 잼.
3. 비용 비교: 놈이 화장실 쓰는 시간이 내가 벤치에 눕고 일어나는(**문맥 전환**) 시간보다 짧으면 밖에서 뺑뺑이(**스핀락**).
4. 뮤텍스 선택: 놈이 화장실에서 똥(I/O, 긴 연산)을 싸면 쿨하게 벤치에 누워서 잠(**뮤텍스**).

#### 한줄 요약

- 자면 안 되거나 금방 끝날 일이면 스핀락, 오래 걸릴 일이면 뮤텍스를 꽂는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 키보드를 치거나 마우스를 움직였을 때 하드웨어가 "이거부터 당장 처리해!"라고 OS 멱살을 잡고 끼어드는 최우선 실행 흐름이다.

</details>

| 비교 항목 | **스핀락** (Spinlock) | **뮤텍스** (Mutex) |
|:---|:---|:---|
| 락 대기 방식 | CPU 100% 찍으면서 `while` 문 **무한 뺑뺑이 (Busy Waiting)** | CPU 놔주고 대기 큐에서 **꿀잠 (Sleep/Block)** |
| 문맥 전환 오버헤드 | 잠들지 않으니까 누웠다 일어나는 지연 속도가 **0(Zero)** | 잠들고 깨어날 때마다 무거운 **문맥 전환 비용** 발생 |
| 찰떡궁합 임계 구역 | 변수 값 하나 딸깍 바꾸는 **초단기 연산 구역** | 디스크 읽거나 네트워크 통신 껴 있는 **장기 체류 구역** |
| **ISR** 사용 가능 여부 | 인터럽트는 잠들면 끝장이니까 무조건 **스핀락** 써야 함 | 인터럽트 안에서는 잠들 수 없으므로 **절대 사용 불가** |

#### 한줄 요약

- 스핀락은 CPU를 태우는 대신 제일 빠르고, 뮤텍스는 문맥 전환 비용이 들지만 딴 놈한테 CPU를 양보한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 라인 바운싱(Cache Line Bouncing)**: 여러 코어가 스핀락 뺏으려고 미친 듯이 TAS명령어를 때려 박으면, 캐시 일관성 맞추느라 CPU 버스가 폭파되는 대참사이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스핀락 돌던 놈이 갑자기 OS한테 CPU 뺏기고 쫓겨나서, 다른 놈들이 무한 스핀 돌고 뻗음 | 스핀락 얻으면 아예 **해당 코어의 선점(Preempt)을 꺼버림** | 락 쥔 놈이 중간에 쫓겨나는 대참사를 막아서 스핀 지옥 예방 |
| 코어들이 개나 소나 스핀락 찌르다가 **캐시 라인 바운싱** 터져서 버스 대역폭 싹 다 말라죽음 | 스핀 루프 안에 `PAUSE` 명령 넣고 번호표 뽑는 **Ticket Lock**으로 갈아탐 | 뇌 빼고 찌르는 짓을 딜레이 시켜서 캐시 일관성 트래픽 급감 |
| 임계 구역 코드가 금방 끝날지 오래 걸릴지 런타임 전엔 도저히 알 수가 없음 | 일단 스핀락 돌다가 안 되면 자버리는 **적응형 뮤텍스(Adaptive Mutex)** 투입 | 런타임 상황에 맞춰 최적의 효율로 눈치껏 대기 모드 변경 |

#### 한줄 요약

- 스핀락 중엔 선점을 끄고, 캐시 폭발은 티켓 락으로 막으며, 잘 모를 땐 적응형 뮤텍스로 비빈다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동기화 대기 방식 선택 기준(Lock Waiting Selection Criteria)**: 코드가 수면 불가(ISR)인지, 얼마나 빨리 끝나는지 따져서 CPU 뺑뺑이를 돌릴지 재울지 정하는 잣대이다.

</details>

- **동기화 대기 방식 선택 기준** 원칙에 따라, ISR과 초단기 임계 구역엔 무조건 **스핀락**을 꽂고, I/O가 껴있는 놈은 **뮤텍스** 채택 기조 확립함

#### 한줄 요약

- 인터럽트나 찰나의 연산엔 스핀락을, 파일 I/O나 장시간 연산엔 뮤텍스를 박아라.
