## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **스핀락(Spinlock)**: 경합 시 CPU에서 잠금 상태를 반복 검사하는 방식이다.
- **뮤텍스(Mutual Exclusion, Mutex)**: 경합한 스레드를 대기 큐에서 재우는 상호 배제 방식이다.

</details>

- 정의/개념: **스핀락과 뮤텍스**는 경합 시 각각 CPU에서 상태를 반복 검사하거나 대기 큐에서 수면하는 **상호 배제 잠금 방식**이다.
- 배경/필요성: 보유시간•수면 가능 여부를 무시하면 **CPU 낭비•전환 비용이 증가한다**.

#### 한줄 요약

- 수면 가능 여부와 보유시간에 따른 **잠금 방식 선택**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **바쁜 대기(Busy Waiting)**: 조건이 충족될 때까지 CPU에서 상태를 반복 검사하는 대기이다.
- **수면 대기(Sleeping Wait)**: 스레드를 대기 큐로 옮겨 CPU를 반납하는 대기이다.
- **락 보유시간(Lock Hold Time)**: 락 획득부터 해제까지 임계 구역을 점유한 시간이다.
- **문맥 전환(Context Switch)**: 현재 스레드의 실행 상태를 저장하고 다른 스레드의 상태를 복원하는 처리이다.
- **수면 가능 문맥**: 스레드가 CPU를 반납하고 운영체제 대기 큐로 이동할 수 있는 실행 상황이다.

</details>

- 스핀락은 **반복 상태 검사**로 문맥 전환 회피가 핵심이다.
- 뮤텍스는 **대기 큐 수면**으로 CPU 점유 반납이 핵심이다.
- **잠금 보유시간•수면 가능 문맥**이 선택 기준이다.

#### 한줄 요약

- 스핀락은 **바쁜 대기**, 뮤텍스는 수면 대기 사용이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **상태 워드(State Word)**: 잠김•해제와 소유권을 원자적으로 기록하는 락 상태 저장소이다.
- **임계 구역(Critical Section)**: 공유 상태를 한 번에 한 스레드만 다루는 코드 범위이다.

</details>

```text
           [경쟁 스레드]
                  |
           [락 상태 워드] -- [대기 방식]
                  |
            [소유 스레드]
                  |
             [임계 구역]
```

선의 의미: 경쟁 스레드는 락 상태 워드를 확인하며 선택된 대기 방식을 따르고, 락 상태 워드는 소유 스레드를 식별하며, 소유 스레드만 임계 구역을 실행한다.

| 구성요소 | 책임 |
|:---|:---|
| 경쟁 스레드 | **락 획득•해제 요청** |
| 락 상태 워드 | **잠김 상태•소유권** 기록 |
| 대기 방식 | **반복 검사•수면 대기** 선택 |
| 임계 구역 | **상호 배제 실행** 범위 |
| 소유 스레드 | 임계 구역 완료 후 **락 해제** |

#### 한줄 요약

- 상태 워드와 **대기 방식**이 소유권 경쟁을 통제한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **수면 가능성 판정**: 현재 문맥이 대기 큐로 이동해 CPU를 반납할 수 있는지 확인하는 단계이다.
- **보유시간•전환비용 비교**: 예상 락 보유시간이 수면•깨움 문맥 전환 비용보다 짧은지 판정하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 잠금 대기 방식 결정         │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 수면 가능성 판정         │
└───────┬──────────────────────┘
        ├─ 수면 불가 ───────────▶ [스핀락]
        │ 수면 가능
        ▼
┌──────────────────────────────┐
│ 2. 보유시간•전환비용 비교   │
└───────┬──────────────────────┘
        ├─ 보유시간 < 전환비용 ─▶ [스핀락]
        └─ 보유시간 ≥ 전환비용 ─▶ [뮤텍스]
```

**동작 원리**

- **1. 수면 가능성 판정**: 커널 문맥의 수면 허용 여부를 확인한다.
- **2. 보유시간•전환비용 비교**: 더 작은 대기 비용의 방식을 선택한다.

#### 한줄 요약

- 수면 불가•짧은 보유는 스핀락, 긴 보유는 **뮤텍스**가 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **소유자 선점(Owner Preemption)**: 락 소유자가 실행 중단되어 대기자가 스핀해도 락을 해제할 수 없는 상태이다.
- **수면 불가 문맥(Non-sleepable Context)**: 현재 실행을 멈추고 스케줄러 대기 큐로 이동할 수 없는 커널 상황이다.

</details>

| 잠금 대기 방식 | 스핀락 | 뮤텍스 |
|:---|:---|:---|
| 적용 기준 | 전환 비용보다 **짧은 보유시간** | 전환 비용보다 **긴 보유시간** |
| 핵심 특징 | CPU에서 **락 상태 반복 조회** | 대기 큐 등록 후 **수면** |
| 한계 | 소유자 선점 시 **CPU 낭비** | 수면 불가 문맥에서 **사용 불가** |

> 요약: 수면 불가•짧은 경합은 **스핀락**, 긴 경합은 **뮤텍스**를 선택한다.

#### 한줄 요약

- 짧은 보유는 **스핀락**, 긴 보유는 **뮤텍스**를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **캐시 라인(Cache Line)**: CPU 캐시와 메모리 사이에서 한 번에 전송•일관성을 관리하는 데이터 블록이다.
- **다중 소켓(Multi-socket)**: 여러 물리 CPU 패키지가 메모리와 캐시 일관성 통신을 공유하는 구조이다.
- **블로킹 락(Blocking Lock)**: 락을 얻지 못한 스레드를 수면 상태로 전환하는 잠금이다.
- **스핀 상한(Spin Limit)**: 락 상태를 반복 검사할 최대 횟수나 시간을 정해 CPU 낭비를 제한하는 값이다.
- **락 분할(Lock Striping)**: 공유 잠금을 여러 독립 잠금으로 나누는 기법이다.
- **데이터 지역화(Data Localization)**: 데이터를 사용하는 CPU 가까이에 배치하는 기법이다.
- **캐시 일관성 트래픽(Cache-coherence Traffic)**: 여러 CPU 캐시에 있는 같은 데이터의 상태를 맞추기 위해 오가는 통신량이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소유자가 선점된 동안 대기자가 계속 **바쁜 대기** | 선점 가능 문맥은 뮤텍스 사용•**스핀 상한 적용** | **CPU 낭비 시간** 제한 |
| 임계 구역이 길어져 짧은 보유시간 **선택 가정 붕괴** | 락 보유•대기시간의 **백분위 계측** | **잠금 방식 재선정** 근거 확보 |
| 다중 소켓에서 상태 워드의 **캐시 라인 왕복** | 락 분할•CPU별 대기 큐와 **데이터 지역화** | **캐시 일관성 트래픽** 감소 |
| 수면 불가 문맥에서 **블로킹 락 사용** | 문맥별 허용 락 규칙과 **정적•실행 중 검사** | **커널 정지•오류** 예방 |

#### 한줄 요약

- 보유시간 계측과 **스핀 상한**으로 CPU 낭비를 제한한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **문맥 전환 비용**: 스레드 상태를 저장•복원하고 스케줄링하는 데 드는 시간이다.

</details>

- 수면 불가•보유시간이 전환비용보다 짧으면 **스핀락**, 그 외에는 **뮤텍스**를 선택한다.

#### 한줄 요약

- 수면 가능 여부와 보유시간으로 **잠금 방식 선택**이 핵심이다.
