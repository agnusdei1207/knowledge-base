## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스핀락(Spinlock)**: 락 획득 실패 시 CPU를 반납하지 않고 `while` 루프를 돌며 즉시 재시도하는 바쁜 대기(Busy-Waiting) 락.
- **뮤텍스(Mutex)**: 락 획득 실패 시 스레드를 수면 큐(Wait Queue)로 전환하고 CPU를 타 프로세스에 양보하는 블로킹 락.

</details>

- 정의/개념: 임계 구역 대기 시 CPU를 점유하며 루프를 도는 **스핀락(Spinlock)** 과 수면 큐로 전환하는 **뮤텍스(Mutex)** 상호 배제 기법
- 배경/필요성: 임계 구역이 극히 짧거나 수면 불가 문맥(ISR)에서 뮤텍스 사용 시 발생하는 **Sleep-Wakeup 문맥 전환 오버헤드 및 성능 저하 한계**

#### 한줄 요약
- 대기 시간이 문맥 전환 비용보다 짧으면 스핀락, 길면 뮤텍스를 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바쁜 대기(Busy-Waiting)**: 락 해제를 기다리며 CPU 사이클을 100% 점유하여 즉각적인 응답성을 얻는 대기 방식.
- **문맥 전환 임계점(Context Switch Threshold)**: 스레드를 Sleep 시키고 깨우는 데 소요되는 커널 오버헤드 시간(수 $\mu s$).

</details>

- **스핀락**: CPU를 점유하는 **바쁜 대기(Busy-Waiting)** 로 문맥 전환 지연을 원천 제거
- **뮤텍스**: CPU를 타 작업에 양보하는 수면(Sleep) 방식으로 **문맥 전환 임계점** 이상의 긴 임계 구역에 적합
- 임계 구역 실행 시간과 **문맥 전환 오버헤드($2 \times T_{\text{ctx}}$)** 간의 상대적 비교가 핵심 선택 기준

#### 한줄 요약
- 극단기 임계 구역은 스핀락으로 지연을 없애고, 긴 임계 구역은 뮤텍스로 CPU 낭비를 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TAS(Test-and-Set) / CAS(Compare-and-Swap)**: 메모리 값을 읽고 새 값으로 쓰는 동작을 단일 원자적 명령어로 수행하는 하드웨어 CPU 인스트럭션.

</details>

```text
[스핀락 vs 뮤텍스 대기 구조 아키텍처]
|-- 하드웨어 원자 명령어 (Atomic CAS / TAS)
|   |-- 락 획득 성공 -> 즉시 임계 구역 진입
|   `-- 락 획득 실패 시 분기:
|-- 스핀락 경로 (Spinlock)
|   |-- CPU 코어에서 `PAUSE` 명령어와 함께 `while(locked)` 루프 반복
|   `-- 커널 개입 없음 (문맥 전환 0, CPU 점유율 100%)
`-- 뮤텍스 경로 (Mutex)
    |-- `futex` 시스템 콜 호출 -> 커널 대기 큐(Wait Queue) 등록
    |-- 현재 스레드 Sleep 상태 전환 및 타 스레드로 CPU 문맥 전환
    `-- 락 해제 시 시그널 수신 후 깨어남 (Wakeup)
```

선의 의미: 계층 및 락 획득 실패 시 처리 분기

| 구성요소 | 책임 |
|:---|:---|
| 하드웨어 CAS/TAS | 락 상태 플래그를 원자적으로 확인하고 점유권 획득 |
| 스핀 루프 (`PAUSE`) | CPU를 양보하지 않고 수 나노초 단위로 락 해제를 즉각 감시 |
| 커널 대기 큐 (`futex`) | 락 획득 실패 스레드를 블로킹 수면 상태로 격리 관리 |
| 선점 비활성화 모듈 | 스핀락 점유 중 해당 코어의 타이머 인터럽트 선점을 차단 |

#### 한줄 요약
- 두 락은 대기 시간을 CPU로 태울지 문맥 전환으로 넘길지에서만 갈리며, 원자적 CAS 실패 이후의 처리 경로가 그 갈림길이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수면 불가 문맥(Non-Sleepable Context)**: 인터럽트 서비스 루틴(ISR)이나 스핀락 내부처럼 프로세스를 Sleep 시킬 수 없는 커널 실행 환경.

</details>

```text
임계 구역 락 획득 요청
        │
   수면 불가 문맥(ISR / 인터럽트 핸들러)인가?
   ┌────┴─────┐
  예           아니오
   │             │
스핀락 강제 선택  임계 구역 실행 예상 시간 < 문맥 전환 오버헤드($2 \times T_{\text{ctx}}$)인가?
(Spinlock)       ┌────┴─────┐
                 예           아니오 (긴 연산 또는 I/O 포함)
                 │             │
             스핀락 선택     뮤텍스 선택 (Mutex)
             (Busy-Wait)    (Sleep & Wakeup)
                 │             │
                 └────┬────────┘
                      │
                 임계 구역 안전 실행 및 락 해제
```

#### 한줄 요약
- 판정 기준은 임계 구역 실행 시간과 문맥 전환 비용의 대소이며, 수면이 불가능한 인터럽트 문맥에서는 그 비교조차 없이 스핀락만 남는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **어댑티브 뮤텍스(Adaptive Mutex)**: 락 보유 스레드가 다른 코어에서 실행 중이면 잠깐 스핀락을 돌고, 수면 중이면 즉시 뮤텍스 수면으로 전환하는 하이브리드 락.

</details>

| 비교 항목 | 스핀락 (Spinlock) | 뮤텍스 (Mutex) | 어댑티브 뮤텍스 (Adaptive Mutex) |
|:---|:---|:---|:---|
| 대기 방식 | **바쁜 대기 (Busy-Waiting)** | **수면 대기 (Sleep & Block)** | 스핀 후 수면 (하이브리드) |
| CPU 소모율 | 대기 중 **CPU 점유율 100%** | 대기 중 CPU 점유율 0% (양보) | 초기 100% 후 0% 전환 |
| 문맥 전환 비용 | **전무 (0 ns)** | 수 마이크로초 ($\mu s$) 발생 | 상황별 최소화 |
| 임계 구역 적합성 | **극단기 연산 ($< 1\mu s$), ISR** | 긴 연산, I/O 작업 ($> 10\mu s$) | 범용 멀티스레드 환경 |
| 단일 코어 사용 | **사용 절대 불가 (데드락 유발)** | 정상 사용 가능 | 정상 사용 가능 |

#### 한줄 요약
- 초단기/ISR은 스핀락, 장기/I/O는 뮤텍스, 범용 환경은 어댑티브 뮤텍스를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 라인 바운싱(Cache Line Bouncing)**: 여러 코어가 단일 메모리 주소에 동시 TAS를 시도하여 MESI 프로토콜로 인해 L1/L2 캐시 라인 무효화가 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스핀락 점유 스레드가 선점(Preemption)당해 타 스레드 무한 스핀 | 스핀락 획득 시 **커널 선점 비활성화(`spin_lock_irqsave`)** | 락 보유 스레드의 중단 방지 및 스핀 시간 최소화 |
| 멀티코어 동시 CAS 시도로 인한 **캐시 라인 바운싱** | 스핀 루프에 **`_mm_pause()` / Ticket Lock** 적용 | 버스 대역폭 낭비 방지 및 캐시 일관성 트래픽 완화 |
| 단일 코어 환경에서 스핀락 사용 시 영구 동결 | 단일 코어 환경에서는 빌드 시 스핀락을 **단순 선점 비활성화**로 치환 | CPU 독점으로 인한 데드락 원천 예방 |
| 임계 구역 소요 시간의 동적 변동 | 런타임에 **적응형 뮤텍스(Adaptive Mutex)** 도입 | 상황에 따른 스핀과 블로킹 자동 전환 최적화 |

#### 한줄 요약
- 스핀락은 문맥 전환을 없애는 대신 대기 시간만큼 CPU를 통째로 태우므로, 임계 구역이 전환 비용보다 짧을 때만 쓰고 그 경계가 불분명하면 어댑티브 락에 판단을 맡긴다.

## Ⅶ. 결론

- 운영체제 커널 및 초고성능 저지연 시스템의 **핵심 락 메커니즘 2대 선택 기준**으로 확립되었으며, 실무에서는 **수 나노초 단위 초단기 락 및 ISR/디바이스 드라이버에는 스핀락(`spin_lock_irqsave`), I/O 및 긴 연산 구간에는 뮤텍스(futex), 범용 멀티코어 환경에서는 초기 스핀 후 수면으로 자동 전환되는 어댑티브 뮤텍스(Adaptive Mutex/Java Biased-Thin Lock)**를 채택

#### 한줄 요약
- 스핀락과 뮤텍스는 임계 구역의 실행 시간과 문맥 전환 비용의 손익분기점을 기준으로 엄격히 구분하여 선택해야 한다.
