## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **바쁜 대기(Spinlock)**: 잠금 획득 실패 시 CPU 제어권을 반납하지 않고 `while` 루프를 반복하며 잠금 해제를 즉각 감시하는 방식.
- **블로킹(Mutex)**: 잠금 획득 실패 시 스레드를 대기 상태(Sleep)로 전환하고 CPU를 타 프로세스에 양보한 뒤 신호로 깨어나는 방식.
- **문맥 전환 오버헤드(Context Switch Overhead)**: 스레드를 재우고 깨우는 과정에서 발생하는 커널 스케줄러 개입 및 레지스터/캐시 복원 지연.

</details>

- 정의/개념: 임계 구역 대기 시 CPU를 점유하며 루프를 도는 **바쁜 대기(Spinlock)** 와 스레드를 수면 큐로 전환하는 **블로킹(Mutex)** 상호 배제 동기화 기법
- 배경/필요성: 초단기 임계구역에서 뮤텍스 사용에 따른 문맥 전환 오버헤드 극복 및 임계구역 길이에 따른 최적 동기화 선택 필요

#### 한줄 요약

- 임계 구역 실행 시간과 문맥 전환 비용의 상대적 크기에 따라 스핀락·뮤텍스를 선택하는 동기화 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바쁜 대기(Busy Waiting)**: 잠금 해제를 기다리는 동안 CPU를 점유하며 `while(locked)` 루프를 반복 실행하는 대기 방식.
- **문맥 전환 임계점(Context Switch Threshold)**: 스레드를 블로킹하고 재개하는 데 소요되는 운영체제 오버헤드 시간으로, 이 값보다 임계 구역 실행 시간이 짧으면 스핀락이 효율적.

</details>

- **스핀락**: CPU를 점유하는 **바쁜 대기** 방식으로 문맥 전환 오버헤드 없음
- **뮤텍스**: CPU를 양보하는 Sleep 방식으로 **문맥 전환 임계점** 이상의 임계 구역에 효율적
- 임계 구역 실행 시간 대비 **문맥 전환 임계점** 상대적 크기가 선택 기준

#### 한줄 요약

- 문맥 전환 비용보다 짧은 임계 구역은 스핀락, 긴 임계 구역은 뮤텍스가 효율적

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **테스트 앤 세트(Atomic Test-and-Set, TAS)**: 잠금 변수 읽기·쓰기를 단일 원자적 명령어로 수행하여 경쟁 조건 없이 잠금 상태를 변경하는 하드웨어 명령어.

</details>

```text
[ 스핀락·뮤텍스 대기 구조 ]
잠금 획득 시도 (TAS 원자 명령어)
├─ 성공: 임계 구역 진입
└─ 실패
    ├─ 스핀락: while(locked) 루프 반복 (CPU 점유)
    └─ 뮤텍스: 커널 대기 큐 진입 (Sleep·CPU 양보)
              └─ 잠금 해제 신호 수신 시 재개
```

선의 의미: 가지(`├─`, `└─`)는 잠금 획득 성패에 따른 처리 방식 분기 관계

| 구성요소 | 책임 |
|:---|:---|
| TAS 명령어 | 잠금 상태 확인·변경을 **원자적** 기반 수행 |
| 스핀 루프 | **바쁜 대기** 방식으로 잠금 해제를 CPU 점유 상태로 대기 |
| 커널 대기 큐 | **뮤텍스** 방식으로 블로킹된 스레드 보관 및 재개 관리 |
| 임계 구역 | 잠금 획득 스레드만 진입 가능한 상호 배제 코드 구간 |

#### 한줄 요약

- TAS 원자 명령어로 잠금을 획득하고, 실패 시 스핀 루프 또는 커널 대기 큐에서 대기

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수면 불가 문맥(Non-Sleepable Context)**: 인터럽트 서비스 루틴(ISR) 등 Sleep이 불허되는 실행 컨텍스트로, 반드시 스핀락을 사용.

</details>

```text
잠금 획득 요청
   │
   ▼
1. 수면 불가 문맥 여부 판정
├─ 수면 불가 (ISR 등): 스핀락 강제 사용
└─ 수면 가능
      │
      ▼
   2. 임계 구역 실행 시간 vs 문맥 전환 비용 비교
   ├─ 임계 구역 시간 < 문맥 전환 비용: 스핀락 선택
   └─ 임계 구역 시간 ≥ 문맥 전환 비용: 뮤텍스 선택
   │
   ▼
3. 잠금 대기·획득·임계 구역 실행·해제
```

**동작 원리** 1. **수면 가능 여부 판정**: ISR 등 수면 불가 문맥에서는 반드시 스핀락 사용
2. **비용 비교**: 임계 구역 실행 시간과 문맥 전환 비용을 비교하여 스핀락·뮤텍스 결정
3. **스핀락 경로**: TAS로 잠금 획득 시도 실패 시 `while` 루프로 CPU 점유 대기
4. **뮤텍스 경로**: TAS 실패 시 커널 대기 큐 진입(Sleep), 잠금 해제 신호 수신 시 재개

#### 한줄 요약

- 수면 불가 여부 → 비용 비교 순서로 스핀락·뮤텍스를 결정하고 잠금 대기 전략 적용

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ISR(Interrupt Service Routine)**: 하드웨어 인터럽트 발생 시 즉시 실행되는 커널 핸들러로, Sleep이 불허되는 수면 불가 문맥.

</details>

| 구분 | 스핀락 (Spinlock) | 뮤텍스 (Mutex) |
|:---|:---|:---|
| 적용 기준 | **수면 불가 문맥** 또는 임계 구역 극단기 실행 | 수면 가능하며 임계 구역이 문맥 전환 비용 이상 소요 |
| 핵심 특징 | CPU 점유 **바쁜 대기**, 문맥 전환 오버헤드 없음 | CPU 양보 Sleep, 재개 시 **문맥 전환 비용** 발생 |
| 한계 | 장기 대기 시 **CPU 낭비**·캐시 라인 경합 발생 | 문맥 전환 오버헤드로 극단기 임계 구역 성능 저하 |

#### 한줄 요약

- ISR·극단기 임계 구역은 스핀락, 수면 가능·장기 임계 구역은 뮤텍스 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 라인 경합(Cache Line Bouncing)**: 복수 코어가 동시에 TAS 명령어를 시도할 때 캐시 일관성 프로토콜(MESI)로 인해 캐시 라인 소유권이 반복 이전되며 버스 대역폭이 소모되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스핀락 보유 스레드 선점으로 다른 스레드의 무한 스핀 발생 | 스핀락 획득 구간에서 **선점(Preemption) 비활성화** | 잠금 보유 스레드의 중간 선점 차단 |
| 멀티코어 TAS 동시 시도로 **캐시 라인 경합** 발생 | 스핀 루프 내 `PAUSE` 명령·Ticket Lock으로 전환 | 캐시 일관성 트래픽 감소 |
| 임계 구역 실행 시간 예측 불가로 최적 방식 미결정 | **적응형 뮤텍스** 적용으로 런타임 실행 상태 기반 전환 | 실행 상황에 따른 최적 대기 방식 자동 선택 |

#### 한줄 요약

- 보유 중 선점은 선점 비활성화로, 캐시 경합은 PAUSE·Ticket Lock으로, 예측 불가는 적응형 뮤텍스로 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **잠금 대기 방식 선택 기준**: 수면 불가 여부·임계 구역 실행 시간과 문맥 전환 비용 비교로 스핀락·뮤텍스를 결정하는 판단 기준.

</details>

- **ISR·극단기 임계 구역** **스핀락**, 수면 가능·장기 I/O 포함 임계 구역은 **뮤텍스** 선택

#### 한줄 요약

- 수면 불가·극단기 임계 구역은 스핀락, 수면 가능·장기 임계 구역은 뮤텍스를 적용
