## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 계보(Data Lineage)**: 원천에서 산출물까지 데이터의 이동•변환•의존 관계와 실행 이력을 연결해 추적하는 메타데이터 체계이다.

</details>

- 정의/개념: 원천에서 산출물까지 데이터의 이동•변환•의존 관계와 실행 이력을 연결하여 추적하는 **데이터 계보(Data Lineage)**
- 배경/필요성: 파이프라인별 문서 분산으로 **변경 영향•오류 원인** 추적 제약

#### 한줄 요약

- 보고서 숫자가 어느 원료와 공정을 거쳐 만들어졌는지 보여 주는 추적 지도이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **열 수준 계보**: 산출 열을 원천 열과 변환식에 연결해 세부 영향 범위를 추적하는 계보이다.
- **방향 그래프**: 데이터셋과 작업 관계를 상류 원천과 하류 소비 방향으로 탐색하는 구조이다.
- **설계•실행 계보 결합**: 선언한 작업 경로와 실제 입출력 이벤트를 비교해 누락과 우회를 찾는 방식이다.

</details>

- 데이터셋•작업 관계를 상•하류로 탐색하는 **방향 그래프**
- 산출 열을 원천 열•변환식과 연결하는 **열 수준 계보**
- 선언 경로와 실제 입출력을 비교하는 **설계•실행 계보 결합**

#### 한줄 요약

- 설계 계보는 예정 노선, 실행 계보는 실제 이동 기록이며 둘 다 빠진 길이 없는지 확인해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **계보 그래프**: 데이터셋•작업•열의 상류와 하류 관계를 저장하는 구성요소이다.
- **검색 화면**: 계보 그래프의 원인과 영향 경로를 탐색하는 구성요소이다.
- **데이터셋**: 네임스페이스와 영속 식별자로 구분하는 계보의 데이터 자산 노드이다.
- **작업**: 데이터셋을 읽어 변환하고 산출물을 만드는 논리 단위이다.
- **실행 이력**: 개별 작업의 상태와 입출력 범위를 기록한 정보이다.
- **부가 메타데이터**: 열 변환식•코드•품질•소유자를 계보 관계에 연결한 정보이다.
- **이벤트 발행기**: 처리 도구에서 계보 이벤트를 생성하는 구성요소이다.
- **수집기**: 계보 이벤트를 모으고 자산 식별자를 정합화하는 구성요소이다.

</details>

```text
[데이터셋] -- [작업•실행 이력] -- [부가 메타데이터]
                         |
              [수집기•이벤트 발행기]
                         |
               [계보 그래프•검색 화면]
```

선의 의미: 작업•실행 이력은 데이터셋과 부가 메타데이터를 연결하고, 수집기•이벤트 발행기는 이 관계를 계보 그래프•검색 화면에 정합화해 상·하류 탐색을 지원한다.

| 구성요소 | 책임 |
|:---|:---|
| 데이터셋 | **네임스페이스•영속 식별자** 로 자산 구분 |
| 작업•실행 이력 | 논리 작업과 **개별 실행 상태•범위** 기록 |
| 부가 메타데이터 | **열 변환식•코드•품질•소유자** 연결 |
| 수집기•이벤트 발행기 | 계보 이벤트 수집과 **식별자 정합화** |
| 계보 그래프•검색 화면 | 데이터셋•작업•열의 **상•하류 탐색** |

#### 한줄 요약

- 보고서 숫자가 어떤 원료와 공정을 거쳤는지 보여 준다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **3. 정합화된 자산•실행 관계**: 시스템별 데이터 자산과 작업 실행을 하나의 방향 그래프로 병합한 결과이다.
- **1. 작업명•실행 식별자**: 오케스트레이터 요청과 후속 계보 이벤트를 같은 실행으로 연결하는 값이다.
- **2. 입출력•열 변환 계보 이벤트**: 실제 읽은 데이터 범위와 열 매핑 및 산출 상태를 기록한 이벤트이다.

</details>

```mermaid
sequenceDiagram
    participant O as 오케스트레이터
    participant E as 처리 엔진
    participant C as 계보 수집기
    participant G as 계보 그래프
    participant U as 사용자
    O->>E: 1. 작업명•실행 식별자
    E->>C: 2. 입출력•열 변환 계보 이벤트
    C->>G: 3. 정합화된 자산•실행 관계
    U->>G: 상•하류 영향 조건
    G-->>U: 원인•책임 경로
```

**동작 원리**

1. **작업명•실행 식별자**: 실행 요청과 이후 계보 이벤트를 같은 실행으로 연결
2. **입출력•열 변환 계보 이벤트**: 실제 읽은 범위와 열 매핑•산출 상태를 실행에 연결
3. **정합화된 자산•실행 관계**: 시스템별 자산과 작업 실행을 하나의 방향 그래프로 병합

#### 한줄 요약

- 작업이 실제로 읽고 쓴 자료와 열 계산식을 운행 기록처럼 모아 관계 지도에 합친다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **실행 계보**: 실제 읽기•쓰기 이벤트를 바탕으로 장애 원인과 감사 경로를 추적하는 계보이다.
- **설계 계보**: 구조화 질의 언어(Structured Query Language, SQL)•작업 그래프•모델 정의를 분석해 배포 전 영향 범위를 찾는 계보이다.

</details>

| 계보 수집 근거 | 설계 계보 | 실행 계보 |
|:---|:---|:---|
| 적용 기준 | **배포 전 영향 분석** | **장애 원인•감사 추적** |
| 핵심 특징 | **SQL•작업 그래프•모델 정의** 분석 | 실제 **읽기•쓰기 이벤트** 관찰 |
| 한계 | 동적 구조화 질의 언어•**수동 데이터 이동** 누락 | 미실행 분기•**미계측 도구** 누락 |

#### 한줄 요약

- 공사 전 영향은 설계도, 사고 후 원인은 실제 운행 기록이 더 잘 보여 준다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **경로 공백**: 일부 처리 엔진이 계보 이벤트를 보내지 않아 영향 경로가 끊기는 문제이다.
- **네임스페이스**: 시스템별 자산 이름의 충돌을 막는 식별 범위이다.
- **영속 식별자**: 자산 이름이 바뀌어도 유지되는 고정 키이다.
- **별칭 이력**: 자산의 과거 이름과 현재 이름을 연결한 기록이다.
- **경로 계측**: 핵심 처리 도구에서 계보 이벤트를 수집하는 통제이다.
- **누락 등록**: 계보를 지원하지 않는 처리 구간을 명시하는 통제이다.
- **입출력 대사**: 계보 관계와 실제 읽기•쓰기 기록을 비교하는 통제이다.
- **신뢰도 표시**: 자동 추론 계보의 확실성을 공개하는 정보이다.
- **표본 검증**: 일부 열 관계를 원천과 대조하는 활동이다.
- **수동 보정**: 잘못 추론한 계보 관계를 책임자가 수정하는 활동이다.
- **실행 이력 분리**: 논리 계보와 대량 실행 기록을 다른 계층에 보관하는 방식이다.
- **실행 이력 집계**: 반복 실행 기록을 요약해 그래프 조회를 줄이는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템별 이름이 겹치면 **자산 관계** 오연결 | **네임스페이스•영속 식별자•별칭 이력** 적용 | 이름 충돌과 **계보 단절** 방지 |
| 일부 처리 엔진이 계보를 보내지 않으면 **경로 공백** 발생 | 핵심 경로 **계측•누락 등록•대사** 적용 | 영향 분석의 **계보 포함률** 향상 |
| 열 변환식을 잘못 추론하면 **열 영향 범위** 오판 | **신뢰도 표시•표본 검증•수동 보정** 적용 | 열 수준 계보의 **정확도** 향상 |
| 개별 실행 이력이 누적되면 **그래프 탐색 지연** 증가 | 논리 계보와 **실행 이력 분리•집계** | 상•하류 경로의 **조회 지연** 감소 |

#### 한줄 요약

- 열 하나를 바꾸기 전에 그 열을 쓰는 보고서와 작업을 찾아 고칠 순서를 정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **적용 시점**: 변경 전 영향 분석과 장애 후 원인 추적을 구분하는 기준이다.

</details>

- 변경 전 영향 분석은 **설계 계보**, 장애 후 원인 추적은 **실행 계보** 우선 적용

#### 한줄 요약

- 예쁜 지도가 아니라 빠진 길 없이 영향과 원인을 빨리 찾는 지도가 필요하다.
