## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 계보(Data Lineage)**: 데이터가 원천 시스템에서 생성되어 변환, 가공을 거쳐 최종 대시보드 및 AI 모델에 도달하기까지의 전체 이동 경로와 의존성을 추적하는 기술.
- **Upstream & Downstream**: 특정 데이터 자산을 기준으로 원천 데이터 방향을 상류(Upstream), 이를 소비하는 파생 데이터 방향을 하류(Downstream)로 정의.

</details>

- 정의/개념: 데이터의 생성 원천부터 변환, 가공, 최종 소비에 이르는 **전체 라이프사이클 경로와 의존성을 방향성 그래프(DAG)로 추적·시각화하는 기술**
- 배경/필요성: 수백 개 이상의 분산 데이터 파이프라인과 변환 작업이 복잡하게 얽힌 환경에서 상류(Upstream) 소스 스키마 변경 시 하류(Downstream) 대시보드 및 AI 모델에 미치는 파급 효과를 사전에 파악하지 못해 발생하는 운영 장애와 지표 결함 발생 시 원인 규명 지연(긴 MTTR)을 해소하기 위해, 데이터의 생성·변환·소비 전 과정을 테이블 및 컬럼 레벨(Column-Level)의 방향성 그래프(DAG)로 추적·시각화하는 데이터 계보(Data Lineage)를 도입하여 **사전 영향도 분석(Impact Analysis)과 신속한 근본 원인 추적(Root Cause Analysis)을 달성**할 필요

#### 한줄 요약
- 계보는 평시에는 값을 만들지 않고 변경과 장애 시점에만 비용을 회수하므로, 수집 범위를 넓힐수록 유지 비용이 늘어 어느 정밀도까지 추적할지가 판단의 핵심이 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Column-Level Lineage**: 테이블 단위의 거시적 추적을 넘어, 특정 계산 컬럼이 어떤 원천 컬럼들의 연산(`price * qty`)으로 도출되었는지 미시적으로 추적.
- **OpenLineage**: Spark, Airflow, Flink, dbt 등의 데이터 도구에서 계보 메타데이터 이벤트를 표준 JSON 규격으로 자동 수집하는 오픈 표준.

</details>

- 소스부터 최종 BI까지 연결하는 **엔드투엔드 파이프라인 추적성(Traceability)**
- 테이블 단위를 넘어 개별 필드 연산까지 추적하는 **컬럼 레벨 정밀 계보(Column-Level Lineage)**
- 스키마 변경 시 파급 효과를 사전에 파악하는 **영향도 분석(Impact Analysis) 지원**

#### 한줄 요약
- 상하류 추적성, 컬럼 레벨 정밀도, 영향도 분석을 통해 데이터 거버넌스를 완성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Lineage DAG 5대 요소**: Dataset Node(데이터 자산), Job Node(변환 작업), Lineage Edge(의존 관계), Emitter(수집 에이전트), Graph Store(계보 저장소).

</details>

```text
[데이터 계보 구성]
|-- 데이터셋 노드
|-- 작업 노드
|-- 계보 엣지
|-- 계보 수집기
`-- 그래프 저장소
```

선의 의미: 계층 및 소스 데이터부터 변환 작업, 마트, 최종 BI 대시보드로 이어지는 상하류 의존성 그래프 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 데이터셋 노드 (Dataset) | 원천 테이블, 중간 파일, 최종 마트 등 **정적인 데이터 자산 개체 표현** | S3 버킷, DB 테이블 |
| 작업 노드 (Job Node) | 데이터를 읽고 쓰는 **Airflow DAG, Spark Job, SQL 쿼리 작업 표현** | 버전 및 실행 이력 포함 |
| 계보 엣지 (Edge) | 입력 데이터와 출력 데이터 간의 **읽기/쓰기 및 컬럼 변환 의존 관계 연결** | 방향성 그래프 (DAG) |
| 계보 수집기 (Emitter) | 파이프라인 실행 시 **OpenLineage 표준 규격으로 입출력 메타데이터 전송** | Airflow/Spark 훅 |
| 그래프 저장소 (Graph) | 수집된 노드와 엣지를 색인하여 **상하류 탐색 질의 및 시각화 제공** | Neo4j, OpenMetadata |

#### 한줄 요약
- 계보 수집기는 파이프라인 실행 지점에 끼어들어 사람이 문서로 관리하던 상하류 의존 관계 기록을 대신하고, 그래프 저장소는 그렇게 모인 노드와 엣지를 영향도 탐색 질의로 되받을 수 있는 색인 계층으로 바꾼다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **계보 수집 및 탐색 5단계**: 파이프라인 실행 $\to$ SQL AST 파싱 $\to$ OpenLineage 이벤트 방출 $\to$ 그래프 DB 적재 $\to$ 상하류 영향도 분석.

</details>

```text
Airflow 및 Spark 데이터 파이프라인 실행
        │
   [실행 이벤트 감지] OpenLineage 에이전트가 Spark 실행 계획 및 SQL 텍스트 감지
        │
   [SQL AST 파싱] 파서가 쿼리를 분석하여 테이블 및 컬럼 간 연산(`A + B -> C`) 추출
        │
   [표준 이벤트 전송] Dataset과 Job의 입출력 관계를 JSON 계보 이벤트로 카탈로그에 전송
        │
   [그래프 DB 적재] 카탈로그가 신규 노드와 엣지를 생성하고 이전 버전과 병합 저장
        │
   개발자가 스키마 변경 전 하류(Downstream) 영향도 분석 및 장애 시 상류(Upstream) 원인 추적
```

#### 한줄 요약
- 코드를 파싱해 얻는 설계 시점 계보는 배포 전에 영향을 알려 주는 대신 실행되지 않은 경로까지 포함하고, 실행 로그에서 얻는 런타임 계보는 정확한 대신 사고가 난 뒤에야 남는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **설계 시점 vs 런타임 계보**: 소스 코드/DDL 기반의 정적 계보(Design-Time)와 실제 파이프라인 실행 로그 기반의 동적 계보(Runtime).

</details>

| 비교 항목 | 설계 시점 계보 (Design-Time Lineage) | 런타임 계보 (Runtime Lineage) |
|:---|:---|:---|
| 수집 원천 | **Git 소스 코드, SQL 스크립트, DDL 정의서** | **Spark, Airflow 실제 실행 런타임 메트릭** |
| 주요 장점 | **코드 배포 전 사전 변경 영향도 검증 가능** | **실제 실행 경로, 데이터 볼륨, 소요 시간 확인** |
| 주요 한계 | 동적 SQL(`EXECUTE IMMEDIATE`) 파싱 한계 | 파이프라인이 실제로 실행되어야만 계보 생성 |
| 최적 적용 단계 | **CI/CD 파이프라인 정적 분석 및 배포 검증** | **실시간 장애 관제 및 지표 왜곡 원인 역추적** |

#### 한줄 요약
- 사전 배포 검증은 설계 시점 계보, 장애 발생 후 원인 분석은 런타임 계보를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Lineage Disconnect**: 외부 API 호출이나 임의의 파이썬 스크립트 사용으로 인해 자동 파서가 입출력 관계를 놓쳐 계보가 끊어지는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 외부 API 호출 및 수동 스크립트로 인한 **계보 단절** | **OpenLineage Custom API 래퍼 작성 및 수동 엣지 주입** | 엔드투엔드 계보 연속성 유지 |
| 소스 DB 컬럼 삭제 시 하류 대시보드 파행 장애 | **CI/CD에 Downstream 영향도 자동 분석 봇 연동** | 장애 파급 사전 차단 |
| 대시보드 지표 오류 발생 시 원인 규명 지연 | **Upstream 역추적으로 결함이 발생한 중간 ETL 작업 즉시 특정** | 장애 복구 시간(MTTR) 90% 단축 |
| 대규모 파이프라인으로 인한 그래프 쿼리 지연 | **최근 실행 스냅샷 캐싱 및 1-Hop 인접 노드 우선 탐색** | 계보 시각화 렌더링 성능 확보 |

#### 한줄 요약
- Custom Emitter 연동, CI/CD 영향도 분석, Upstream 원인 역추적, 그래프 캐싱으로 운영한다.

## Ⅶ. 결론

- 엔터프라이즈 데이터 품질 감사, 규제 컴플라이언스(GDPR/BCBS 239) 준수 및 파이프라인 신뢰성 확보의 **핵심 데이터 거버넌스 기술**로 확립되었으며, 실무 구축 시에는 **OpenLineage 표준 기반의 Spark/Airflow 런타임 계보 자동 수집, CI/CD 배포 파이프라인과 연계한 사전 하류 영향도 분석(Impact Analysis) 봇 운영, 미시적 필드 변환을 추적하는 컬럼 레벨 계보(Column-Level Lineage) 및 단절 없는 커스텀 에미터(Emitter) 거버넌스**를 결합하여 데이터 운영 안정성과 변경 민첩성을 동시 확보

#### 한줄 요약
- 데이터 계보는 데이터의 이동과 변환 전 과정을 시각화하여 변경 영향도와 장애 원인을 신속히 규명하는 현대 데이터 엔지니어링의 필수 거버넌스 기술이다.
