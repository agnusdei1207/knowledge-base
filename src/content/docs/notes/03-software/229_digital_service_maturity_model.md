## 미리 알고가기

- **디지털 서비스(Digital Service)**: 사용자의 목적 달성을 위해 사람, 업무, 데이터와 기술을 처음부터 끝까지 연결한 서비스다.
- **성숙도 모형(Maturity Model)**: 조직의 역량이 임시 대응에서 반복 가능하고 지속 개선되는 상태로 발전하는 수준을 단계로 표현한 모형이다.
- **역량 차원(Capability Dimension)**: 사용자 경험, 운영, 데이터, 기술, 조직처럼 성숙도를 나누어 평가하는 독립 영역이다.
- **서비스 성과(Service Outcome)**: 처리 완료율, 소요시간, 만족도처럼 사용자가 실제로 얻은 결과를 나타내는 지표다.
- **증거 기반 평가**: 설문 의견만이 아니라 산출물, 운영 자료와 측정값으로 현재 수준을 판정하는 방식이다.
- **현재 수준표**: 역량 차원별 현재 단계와 판정 근거를 함께 나타낸 평가 결과다.
- **목표 수준표**: 사업 목표와 투자 여건을 반영해 역량 차원별로 도달할 단계를 정한 상태다.
- **개선 로드맵**: 현재와 목표의 차이를 줄일 과제, 책임자, 순서와 완료 시점을 정한 계획이다.
- **성과 제약 역량**: 다른 역량이 높아도 서비스 성과 향상을 제한하는 취약 능력이다.

## Ⅰ. 개요

- 정의/개념: 디지털 서비스의 **역량 수준 진단·개선 경로 결정**
- **배경/필요성**: 기술 투자와 **사용자 성과 불일치 한계** 해소

### 쉽게 이해하기 (학습용)

- 새 기술을 얼마나 샀는지가 아니라 사용자가 일을 끝내는 능력이 어느 단계인지 증거로 확인하고 다음 개선 순서를 정한다.

## Ⅱ. 특징

- 단계별 **역량 반복 가능성 표현**
- 차원별 편차의 **성과 제약 역량 식별**
- 사업 성과·투자 여건 기반 **목표 수준 설정**

### 쉽게 이해하기 (학습용)

- 모든 영역을 최고 단계로 만들기보다 서비스 결과를 막는 약한 영역을 찾아 필요한 수준까지만 먼저 높인다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    A["서비스 성과"] -->|평가 목적| B["역량 차원"]
    B -->|단계별 판정| C["성숙 기준"]
    D["평가 증거"] -->|산출물·측정값| C
    C -->|현재·목표 수준| E["개선 로드맵"]
    E -->|개선 결과| A
```

| 설계 요소 | 설명 |
|:---|:---|
| 서비스 성과 | 사용자·업무 결과와 평가 범위 확정 |
| 역량 차원 | 경험·운영·데이터·기술·조직 분리 |
| 성숙 기준 | 차원별 단계와 통과 조건 정의 |
| 평가 증거 | 산출물·운영 자료·측정값을 수집 |
| 개선 로드맵 | 수준 격차별 과제·책임·순서 결정 |

> 요약: 차원별 증거와 성과 병목으로 개선 결정

### 쉽게 이해하기 (학습용)

- 원하는 서비스 결과를 정하고 여러 능력을 증거로 평가한 뒤 가장 큰 수준 차이를 줄일 과제를 순서대로 배치한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant 서비스책임자
    participant 평가팀
    participant 증거저장소
    participant 개선팀
    서비스책임자->>평가팀: 평가 범위 합의
    평가팀->>증거저장소: 평가 증거 수집
    평가팀->>평가팀: 차원별 수준 판정
    평가팀->>서비스책임자: 병목 역량 식별
    서비스책임자->>개선팀: 목표 수준 설정
    개선팀->>서비스책임자: 개선 로드맵 실행
    서비스책임자->>평가팀: 성과·수준 재평가
```

| 절차 | 설명 |
|:---|:---|
| 평가 범위 합의 | 대상 서비스·성과·차원을 확정 |
| 평가 증거 수집 | 산출물·운영 자료·측정값 확보 |
| 차원별 수준 판정 | 단계 조건과 증거를 대조 |
| 병목 역량 식별 | 성과를 제한하는 취약 차원 선정 |
| 목표 수준 설정 | 사업 목표·비용에 맞춰 단계 결정 |
| 개선 로드맵 실행 | 과제·책임자·순서에 따라 개선 |
| 성과·수준 재평가 | 결과 지표와 단계 변화를 확인 |

> 요약: 증거로 병목을 찾아 개선 후 성과 재평가

### 쉽게 이해하기 (학습용)

- 현재 능력을 자료로 판정하고 서비스 결과를 가장 막는 약점을 먼저 고친 뒤 실제 성과가 나아졌는지 다시 측정한다.

## Ⅴ. 종류 및 비교

| 디지털 서비스 성숙도 | 초기 단계 | 관리 단계 | 최적화 단계 |
|:---|:---|:---|:---|
| 적용 기준 | 절차·책임·증거가 불명확 | 공통 방식과 측정이 정착 | 예측·실험 기반 개선이 반복 |
| 핵심 특징 | 개인 경험 의존 임시 대응 | 표준 절차·지표의 반복 관리 | 성과 자료 기반 지속 개선 |
| 한계 | 품질 편차·담당자 의존 | 절차 준수의 목적화 | 과도한 자동화·지표 최적화 |

> 요약: 반복 가능성과 성과 환류로 단계 판정

### 쉽게 이해하기 (학습용)

- 사람마다 다르게 처리하면 초기, 같은 절차와 지표로 관리하면 관리, 결과 자료로 방법을 계속 바꾸면 최적화 단계다.

## Ⅵ. 실무 사례

1. 민원 완료율의 **제약 구간을 본인확인에서 식별**

### 쉽게 이해하기 (학습용)

- 온라인 민원 신청의 중도 이탈이 본인확인 단계에 몰리면 그 구간의 사용 경험을 먼저 개선한다.

## Ⅶ. 결론

- 디지털 서비스 역량을 실질적인 사용자 성과로 개선하기 위해 **전략·사용자 경험·데이터·기술·운영 차원의 증거와 성과 제약**을 검토하고, 병목 역량 중심으로 목표 성숙도와 개선과제를 결정한다

### 쉽게 이해하기 (학습용)

- 전체 평균이나 최고 단계보다 사용자 결과를 막는 역량을 증거로 찾아 현실적인 목표와 개선 순서를 정해야 한다.
