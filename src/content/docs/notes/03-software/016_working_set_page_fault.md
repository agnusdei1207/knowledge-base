## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **워킹 셋(Working Set)**: 프로그램이 당장 일하는 데 무조건 필요한, 방금 전까지 미친 듯이 썼고 앞으로도 계속 쓸 핵심 메모리 페이지들의 알짜배기 모음이다.
- **페이지 폴트(Page Fault)**: CPU가 데이터를 내놓으라고 윽박질렀는데 램에 없어서, OS가 헐레벌떡 하드디스크로 데이터 퍼 나르러 뛰어가는 대참사(예외)이다.
- **페이지 폴트 빈도(Page Fault Frequency, PFF)**: 폴트가 너무 자주 터지면 "메모리 쪼들리냐?" 하며 프레임을 더 주고, 잠잠하면 "너 메모리 남네" 하며 뺏어버리는 눈치 게임 알고리즘이다.

</details>

- 정의: 프로세스가 자주 찾는 메모리 덩어리인 **워킹 셋**을 추적하고, 램에 데이터가 없어 디스크를 긁는 **페이지 폴트** 빈도를 멱살 잡고 제어하는 동적 프레임 할당 메커니즘
- 배경: 프로그램마다 필요한 메모리 양이 실시간으로 널뛰는데, 처음부터 프레임을 고정으로 던져주면 **과대/과소 할당**으로 스레싱(Thrashing)이 터지기 때문

#### 한줄 요약

- 프로그램이 찜한 핵심 메모리(워킹 셋)를 챙겨주고, 하드디스크를 자주 긁으면(폴트 빈도 상승) 메모리를 더 부어주는 동적 할당 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워킹 셋 윈도우(Working Set Window, Δ)**: "최근 1만 번의 메모리 접근"처럼, 워킹 셋을 계산하기 위해 과거를 훑어보는 감시 기간의 크기이다.
- **참조 국부성(Locality of Reference)**: 프로그램은 한 번 꽂힌 데이터나 그 근처 코드를 계속 파고드는 습성이 있다는, 가상 메모리 시스템의 근본적인 믿음이다.

</details>

- 프로그램의 쏠림 현상인 **참조 국부성(Locality)**을 믿고 프레임을 탄력적으로 줬다 뺏음.
- 감시 기간인 **워킹 셋 윈도우($\Delta$)** 크기에 따라 워킹 셋 덩치가 고무줄처럼 늘었다 줄었다 함.
- **PFF** 상하한선을 그어놓고, 폴트가 터질 때마다 선을 넘는지 감시해서 선제적으로 프레임을 꽂아 넣음.

#### 한줄 요약

- 쏠림 현상을 이용해 감시 기간 단위로 핵심 메모리를 추려내고, 폴트 상하한선으로 프레임 뺏기/주기를 시전한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PFF 상하한선(Upper / Lower Bound)**: 페이지 폴트가 상한선을 뚫으면 "위험하니까 프레임 더 줘라", 하한선 밑이면 "남아도니까 뺏어라"라고 결정짓는 마지노선이다.

</details>

```text
[ 동적 프레임 할당 십자포화 아키텍처 ]
         [ 프로세스 참조 이력 ]
                │
        ┌───────┴───────┐
        ▼               ▼
[ 워킹 셋 추적기 ]  [ 폴트 빈도 감시기 ]
(윈도우 훑어봄)     (디스크 긁는 횟수 잼)
        │               │
        └───────┬───────┘
                ▼
      [ 동적 프레임 할당기 ]
  (램을 더 주거나, 남는 걸 뺏음)
```

| 구성요소 | 책임 |
|:---|:---|
| 참조 윈도우 ($\Delta$) | 과거 $\Delta$ 시간 동안 놈이 무슨 페이지를 찔러봤는지 장부에 집요하게 기록하는 감시망 |
| **워킹 셋 추적기** | 장부 기록을 긁어모아서, 놈이 지금 당장 숨 쉬는 데 필요한 최소 물리 프레임 개수를 뽑아내는 계산기 |
| 페이지 폴트 처리기 | 램에 없는 거 찾을 때마다 예외 띄우고 디스크 뛰어가면서, **폴트 빈도(PFF)** 수치를 갱신하는 놈 |
| 동적 프레임 할당기 | 폴트 빈도가 **상한선**을 뚫으면 램을 쑤셔 넣어주고, 하한선 밑으로 널널하면 가차 없이 램을 뺏어버리는 일진 |

#### 한줄 요약

- 추적기와 감시기가 워킹 셋과 폴트 빈도를 재면, 할당기가 그에 맞춰 램을 더 주고 뺏는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트 갱신(Page Fault Update)**: 램에 없어서 에러가 터질 때만 폴트 간격을 계산하고 상하한선을 비교해서, 잉여 프레임을 회수할지 고민하는 타이밍이다.

</details>

```text
[ 워킹 셋·폴트율 기반 프레임 제어 흐름 ]
╔════════════════════════════════╗
║ 1. 페이지 참조 및 폴트 감시    ║
║   (메모리 계속 찔러봄)         ║
║              │                 ║
║              ▼                 ║
║ 2. 워킹 셋·폴트율 계산         ║
║   (지금 얼마나 쪼들리나 잼)    ║
║              │                 ║
║              ▼                 ║
║ 3. PFF 상하한선 판정           ║
║   ├─ 빡셈 (상한선 돌파)        ║
║   │        └─▶ 4. 프레임 증설  ║
║   ├─ 널널함 (하한선 밑돔)      ║
║   │        └─▶ 5. 프레임 뺏음  ║
║   └─ 적정 ─────▶ 냅둠          ║
╚════════════════╤═══════════════╝
                 ▼
         [ 할당 밸런스 유지 ]
```

### 동작 원리

1. 참조 및 갱신: $\Delta$ 윈도우 내 프로세스의 참조 비트를 감시함.
2. 산정: 고유 집합 크기(**워킹 셋**)와 디스크를 긁는 간격(**페이지 폴트 빈도**)을 산출함.
3. 상태 판정: 폴트 빈도를 **PFF 상하한선** 마지노선과 비교함.
4. 프레임 증설: 폴트 빈도가 상한선을 뚫어버리면 스레싱 직전이므로 멱살 잡고 프레임을 추가 투입함.
5. 프레임 회수: 폴트 빈도가 하한선 밑으로 놀고먹으면 남아도는 프레임들을 싹 회수함.

#### 한줄 요약

- 폴트 빈도를 재서 선을 넘으면 프레임을 더 주고, 선 밑이면 미련 없이 프레임을 뺏어온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **워킹 셋 알고리즘(Working Set Algorithm)**: 시간이 흐를 때마다 계속 장부를 뒤져가며 워킹 셋을 칼같이 계산하는 무식하게 부지런한 방식이다.
- **PFF 알고리즘(Page Fault Frequency Algorithm)**: 평소엔 놀다가 램에 없어서 에러(페이지 폴트)가 터졌을 때만 간격을 재서 프레임을 조절하는 가성비 방식이다.

</details>

| 비교 항목 | **워킹 셋(Working Set)** 알고리즘 | **PFF (페이지 폴트 빈도)** 알고리즘 |
|:---|:---|:---|
| 프레임 재조정 시점 | $\Delta$ 윈도우마다 **쉬지 않고 계속** 관찰하고 조정함 | 램에 없어서 **페이지 폴트가 터지는 그 순간에만** 조정함 |
| 시스템 오버헤드 | 계속 참조 비트 까보면서 장부 정리하느라 CPU 낭비 심함 | 에러 터질 때만 일하니까 런타임 오버헤드가 확 줄어듦 |
| 핵심 튜닝 요소 | **워킹 셋 윈도우($\Delta$)** 크기를 얼마나 길게 잡느냐 | **상한선(Upper) / 하한선(Lower)** 간격을 얼마나 주느냐 |
| 장단점 | 확실하게 메모리를 챙겨주지만 계산병 걸려서 느려짐 | 가성비 좋게 스레싱을 막지만 폴트 전까진 사태 파악을 못 함 |

#### 한줄 요약

- 워킹 셋은 매번 감시해서 정확하지만 무겁고, PFF는 에러 날 때만 일해서 가볍다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **순차 스캔(Sequential Scan)**: DB 백업이나 풀스캔 때처럼, 다시 안 볼 데이터를 한 번씩 싹 훑고 지나가서 애먼 워킹 셋 장부를 쓰레기로 오염시키는 민폐 작업이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워킹 셋 추적한답시고 계속 계산기 두드리느라 CPU 오버헤드 터짐 | 페이지 폴트 터질 때만 일하는 **PFF**로 노선 변경함 | 평시 오버헤드를 대폭 썰어버려서 가성비 극대화 |
| $\Delta$ 윈도우 크기를 잘못 잡아서 프레임을 너무 주거나 다 뺏어버림 | 워크로드 패턴 냄새 맡고 런타임에 $\Delta$ 크기를 동적으로 가변 튜닝함 | 메모리 파편화 및 낭비 차단 |
| DB 풀스캔 도는데 워킹 셋에 한 번 쓰고 버릴 쓰레기가 꽉 참 | 최신 트렌드만 보는 게 아니라 과거 이력까지 보는 **LRU-K** 교체 방식을 섞음 | 스캔성 데이터가 진짜 알짜배기 워킹 셋을 밀어내는 대참사 원천 봉쇄 |

#### 한줄 요약

- 오버헤드는 PFF로 줄이고, 윈도우 튜닝으로 낭비를 막으며, 쓰레기 데이터는 LRU-K로 거른다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동적 프레임 할당 기준(Dynamic Frame Allocation Criteria)**: 폴트 빈도 상하한선, 워킹 셋 윈도우 크기를 튜닝해서, CPU와 메모리의 피 터지는 줄다리기를 중재하는 설계 잣대이다.

</details>

- **동적 프레임 할당 기준** 원칙에 따라, 가상 메모리 관리 시 정확도를 위한 **Working Set 추정**과 가성비를 위한 **PFF 저비용 알고리즘** 상호 보완 적용 기조 확립함

#### 한줄 요약

- 정확성을 위한 워킹 셋 추정과 가성비를 위한 PFF 방식을 섞어서 가상 메모리를 튜닝한다.
