## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **소프트웨어(Software, SW)**: 컴퓨터가 기능을 수행하도록 만든 프로그램•데이터•관련 산출물의 집합이다.
- **기능점수(Function Point, FP)**: 구현 기술과 무관하게 사용자 관점의 입력•출력•조회•내부•외부 데이터 기능을 분류하고 가중치를 적용해 소프트웨어 논리 규모를 재는 방법이다.
- **개발 전 규모 비교**: 코드를 작성하기 전에 요구 기능을 공통 단위로 비교하는 활동이다.

</details>

- 정의/개념: 사용자 기능을 유형별로 분류하고 가중치를 적용하는 구현 독립적 **기능점수** 측정 방법이다.
- 배경/필요성: 코드 줄 수는 언어•구현 방식에 따라 달라 **개발 전 규모 비교**에 적합하지 않다.

#### 한줄 요약

- **소프트웨어**의 사용자 기능 유형과 가중치에 기반한 **기능점수** 측정이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **기술 독립적 사용자 기능**: 프로그래밍 언어나 구현 방식과 무관하게 사용자가 식별하는 기능이다.
- **외부 입력(External Input, EI)**: 외부에서 내부 논리 파일을 변경하는 입력 기능이다.
- **외부 출력(External Output, EO)**: 계산을 포함해 외부로 데이터를 내보내는 출력 기능이다.
- **외부 조회(External Inquiry, EQ)**: 계산 없이 데이터를 조회하는 입출력 기능이다.
- **내부 논리 파일(Internal Logical File, ILF)**: 측정 대상이 유지하는 논리 데이터 집합이다.
- **외부 연계 파일(External Interface File, EIF)**: 외부 시스템이 유지하고 측정 대상이 참조하는 데이터이다.
- **시스템 경계(System Boundary)**: 측정 대상의 안과 밖을 구분하는 기준이다.
- **복잡도 규칙(Complexity Rule)**: 기능 유형별 가중치를 판정하는 기준이다.

</details>

- **기술 독립적 사용자 기능**으로 논리 규모를 측정한다.
- **외부 입력**, **외부 출력**, **외부 조회**, **내부 논리 파일**, **외부 연계 파일**의 수와 복잡도를 합산한다.
- **시스템 경계**와 **복잡도 규칙**으로 측정 편차를 통제한다.

#### 한줄 요약

- **기술 독립적 사용자 기능**의 다섯 유형이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **트랜잭션 기능**: 사용자가 경계를 통해 데이터를 입력•출력•조회하는 EI•EO•EQ 기능이다.
- **데이터 기능**: 대상이 유지하는 ILF와 외부에서 유지해 참조하는 EIF 기능이다.

</details>

```text
[기능점수(FP)]
+-- [트랜잭션 기능]
|   +-- [외부 입력(EI)]
|   +-- [외부 출력(EO)]
|   +-- [외부 조회(EQ)]
+-- [데이터 기능]
    +-- [내부 논리 파일(ILF)]
    +-- [외부 연계 파일(EIF)]
```

선의 의미: 기능점수는 트랜잭션 기능과 데이터 기능으로 나뉘며, 트랜잭션 기능은 EI•EO•EQ를 포함하고 데이터 기능은 ILF•EIF를 포함한다.

| 구성요소 | 책임 |
|:---|:---|
| 기능점수(FP) | 다섯 기능 유형의 가중 논리 규모 합산 |
| 트랜잭션 기능 | 경계의 입력•출력•조회 기능 분류 |
| 데이터 기능 | 논리 데이터의 유지•참조 책임 분류 |
| 외부 입력(EI) | 외부 입력으로 내부 상태 갱신 |
| 외부 출력(EO) | 계산•가공한 파생 정보 전달 |
| 외부 조회(EQ) | 상태 변경 없는 조회 응답 |
| 내부 논리 파일(ILF) | 측정 대상이 유지하는 논리 데이터 |
| 외부 연계 파일(EIF) | 외부가 관리하는 참조 데이터 |

#### 한줄 요약

- **트랜잭션 기능**과 **데이터 기능**으로 나뉘는 다섯 기능 유형 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **측정 범위(Measurement Scope)**: 기능점수 산정에 포함할 대상을 정한 범위이다.
- **경계 기준(Boundary Criteria)**: 데이터 유지 책임으로 시스템 안팎을 구분하는 기준이다.
- **다섯 기능 유형 목록**: EI•EO•EQ•ILF•EIF로 식별한 사용자 기능 목록이다.
- **데이터 요소 유형(Data Element Type, DET)**: 사용자가 식별하는 필드 유형이다.
- **레코드 요소 유형(Record Element Type, RET)**: 논리 파일의 하위 레코드 그룹 유형이다.
- **참조 파일 유형(File Type Referenced, FTR)**: 트랜잭션이 참조하거나 유지하는 논리 파일 유형이다.
- **가중 기능점수**: 기능 유형별 개수에 복잡도 가중치를 곱해 합산한 규모이다.
- **측정 범위•시스템 경계 확정**: 측정 대상과 데이터 유지 책임의 안팎을 정하는 동작이다.
- **다섯 기능 유형 식별**: 사용자 목적에 따라 EI•EO•EQ•ILF•EIF를 중복 없이 분류하는 동작이다.
- **DET•RET•FTR 계수**: 사용자 필드와 레코드 그룹 및 참조 파일 유형의 수를 세는 동작이다.
- **복잡도 가중치•기능점수 합산**: 유형별 개수와 가중치를 곱해 전체 논리 규모를 계산하는 동작이다.
- **기능 개수($N_t$)**: 기능 유형 $t$의 개수이다.
- **복잡도 가중치($W_t$)**: 기능 유형 $t$에 적용하는 가중치이다.

</details>

```text
[측정 목적•사용자 요구]
          |
          v
+----------------------------------+
| 1. 측정 범위•시스템 경계 확정   |
+----------------------------------+
          |
          v
+----------------------------------+
| 2. 다섯 기능 유형 식별          |
+----------------------------------+
          |
          v
+----------------------------------+
| 3. DET•RET•FTR 계수             |
+----------------------------------+
          |
          v
+----------------------------------+
| 4. 복잡도 가중치•기능점수 합산 |
+----------------------------------+
          |
          v
[검토된 논리 규모 FP]
```

### 동작 원리

1. **측정 범위•시스템 경계 확정**: **측정 범위**와 **경계 기준**으로 유지 책임을 분리한다.
2. **다섯 기능 유형 식별**: **다섯 기능 유형 목록**을 작성한다.
3. **DET•RET•FTR 계수**: **데이터 요소 유형**, **레코드 요소 유형**, **참조 파일 유형**을 집계한다.
4. **복잡도 가중치•기능점수 합산**: **가중 기능점수**를 산정한다.

전체 기능점수는 유형별 **기능 개수**와 **복잡도 가중치**의 곱을 합산해 계산한다.

$$FP=\sum_{t \in \{EI,EO,EQ,ILF,EIF\}} N_t \times W_t$$

> 요약: 시스템 경계 안의 다섯 사용자 기능을 식별하고 복잡도 가중치를 합산한다.

#### 한줄 요약

- 경계•유형•복잡도 기반 **기능점수 산정 흐름**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **코드 줄 수(Lines of Code, LOC)**: 구현된 소스 코드의 물리적 줄 수로 규모를 나타내는 단위이다.

</details>

| 규모 산정 방식 | 기능점수 FP | LOC 기반 규모 산정 |
|:---|:---|:---|
| 적용 기준 | 구현 전 논리 기능 규모 산정 | 구현 후 물리적 코드량 산정 |
| 핵심 특징 | **기술 독립적 사용자 기능** 측정 | 소스 코드 라인 수 측정 |
| 한계 | 경계•복잡도 판정 편차 | 언어•코딩 방식별 비교 왜곡 |

> 요약: 코드 라인은 길이, 기능점수는 기능 규모를 측정한다.

#### 한줄 요약

- 구현 전 규모는 **기능점수**, 구현 후 코드량은 **코드 줄 수**로 측정한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **측정 목적(Measurement Purpose)**: 기능점수를 산정하고 사용할 이유이다.
- **연계 대상(External Interface)**: 측정 대상과 데이터를 교환하는 외부 시스템이다.
- **사용자 목적(User Goal)**: 사용자가 기능으로 인식하는 업무 목표이다.
- **독립 처리(Elementary Process)**: 사용자 관점에서 완결된 최소 업무 처리이다.
- **비기능 요구(Non-functional Requirement)**: 기능 규모 외에 비용을 좌우하는 품질 조건이다.
- **위험(Risk)**: 개발 비용과 일정에 영향을 주는 불확실성이다.
- **역량(Capability)**: 개발 조직이 기능을 구현할 수 있는 수행 수준이다.
- **상태 변경(State Change)**: 트랜잭션이 내부 데이터를 갱신하는 처리이다.
- **계산(Derived Calculation)**: 입력으로 파생 정보를 만드는 처리이다.
- **유지 책임(Maintenance Responsibility)**: 논리 데이터를 관리하는 시스템의 책임이다.
- **교육(Training)**: 측정자가 기능점수 규칙을 학습하는 통제이다.
- **동료 검토(Peer Review)**: 다른 측정자가 기능 분류를 확인하는 통제이다.
- **기준 사례(Reference Case)**: 표준 판정 예를 재사용하는 편차 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 측정자마다 시스템 경계를 달리 잡아 규모 편차 발생 | **측정 목적**, **시스템 경계**, **연계 대상** 사전 합의 | 규모 산정 편차 감소 |
| 같은 사용자 기능을 화면•외부 인터페이스별로 중복 계수 | **사용자 목적**과 **독립 처리**로 식별 | 기능 중복 계수 방지 |
| 상태 변경•계산•유지 책임을 혼동해 유형 오분류 | **상태 변경**, **계산**, **유지 책임** 기록 | 기능 유형 판정 일관성 확보 |
| DET•RET•FTR 해석 차이로 복잡도 가중치 편차 | **교육**, **동료 검토**, **기준 사례** 운영 | 측정자 해석 차이 축소 |
| 기능점수를 비용으로 바로 환산해 품질•위험 누락 | **비기능 요구**, **위험**, **역량** 별도 보정 | 비용 추정 왜곡 방지 |

> 적용 사례: 공공 소프트웨어 사업은 기능점수와 단가로 개발•변경 대가 산정

#### 한줄 요약

- **측정 목적**, **시스템 경계**, **독립 처리**에 기반한 편차 통제가 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **복잡도 근거(Complexity Rationale)**: 기능 가중치 판정 이유를 기록한 정보이다.
- **기능점수 확정**: 검토된 기능 목록과 복잡도 가중치를 합산해 공식 규모로 승인하는 활동이다.

</details>

- **시스템 경계**, **다섯 기능 유형 목록**, **복잡도 근거**로 **기능점수 확정**을 수행한다.

#### 한줄 요약

- 경계•유형•복잡도 근거 기반 **기능점수 확정**이 핵심이다.
