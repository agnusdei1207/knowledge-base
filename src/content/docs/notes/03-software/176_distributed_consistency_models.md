## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Consistency Model(일관성 모델)**: 분산 복제본 환경에서 읽기/쓰기 연산의 순서와 시점이 클라이언트에게 어떻게 관찰되는지를 규정하는 정합성 계약.

</details>

- 정의/개념: 분산 복제본 환경에서 읽기와 쓰기 연산의 **관찰 순서와 최신성 보장 수준을 정의하는 분산 시스템 정합성 계약 규약**
- 배경/필요성: 분산 복제는 쓰기 하나를 모든 복제본에 반영하는 동안 대기와 조율 비용을 치르므로, 그 비용을 어디까지 낼지를 정족수(N·W·R)와 일관성 모델로 계층화해 도메인마다 다른 지연·정합 수준을 고를 필요

#### 한줄 요약
- 비즈니스 도메인 요구에 맞춰 선형성부터 최종 일관성까지 최적의 일관성 모델을 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Quorum 교차 조건**: $W+R>N$으로 읽기·쓰기 복제본 집합의 교집합을 확보하는 조건.
- **Read-Your-Writes**: 사용자가 자신이 직접 수정한 데이터만큼은 새로고침 시 즉시 최신값으로 관찰되도록 보장하는 세션 일관성.

</details>

- 일관성 강도가 높을수록 동기화 대기로 지연시간이 증가하는 **Latency vs Consistency**
- 강력한 합의일수록 단일 노드 장애 시 쓰기를 거부하는 **Availability vs Consistency**
- 정족수와 버전 정보를 통한 **정합성·지연 조정**

#### 한줄 요약
- 일관성 강도와 응답 지연 및 가용성 간의 트레이드오프를 통해 최적의 정합성 계층을 설계한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정족수(Quorum) 기반 일관성 구조**: $N$(복제본 수), $W$(쓰기 정족수), $R$(읽기 정족수), Conflict Resolution(충돌 해결 규칙).

</details>

```text
[Quorum 기반 일관성 제어 시스템]
├── 전체 물리적 구조
│   └── 복제본 수 (N)
├── 정족수 합의 계층
│   ├── 쓰기 정족수 (W)
│   └── 읽기 정족수 (R)
└── 데이터 정합성 계층
    └── 충돌 해결 규칙
```

선의 의미: 계층 및 클라이언트의 요청을 조정자 노드가 정족수 공식에 따라 복제본 노드들에 전파하고 충돌을 해결하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 복제본 수(N) | 전체 데이터 복제본 수 정의 |
| 쓰기 정족수(W) | 쓰기 성공에 필요한 응답 수 정의 |
| 읽기 정족수(R) | 읽기에서 조회할 복제본 수 정의 |
| 충돌 해결 규칙 | **버전 벡터·LWW**로 동시 쓰기 해소 |

#### 한줄 요약
- N·W·R 세 숫자의 조합만으로 강한 읽기와 낮은 지연 사이의 지점이 정해지므로, 일관성 수준이 애플리케이션 코드가 아니라 정족수 설정값으로 표현된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **선형화 가능한 쓰기**: 리더 순서 부여, 정족수 복제, 커밋 응답.

</details>

```text
[쓰기 요청 수신] 클라이언트 쓰기 명령 접수
        │
   1. [로그 순서 결정] 리더가 쓰기에 로그 인덱스 부여
        │
   2. [과반수 복제 커밋] 과반수 로그 복제 후 Commit 확정
        │
   3. [성공 반환] 클라이언트에게 쓰기 성공을 통지하여 Linearization Point 형성
        │
[선형화 읽기] 리더·Read Index 등 선형화 절차로 결과 반환
```

동작 원리:

1. 로그 순서 결정: 리더가 쓰기 순서 확정
2. 과반수 복제 커밋: 정족수 복제 후 커밋
3. 성공 반환: 커밋 시점을 선형화 지점으로 통지

#### 한줄 요약
- 과반수 커밋을 기다릴수록 응답은 늦어지지만 이후 읽기가 최신값을 보장받으므로, 대기 시간과 Stale Read 위험은 같은 자원을 나눠 갖는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **5대 일관성 모델**: Linearizability(선형성), Sequential(순차), Causal(인과), Session(세션), Eventual(최종).

</details>

| 일관성 모델 | 보장 강도 | 핵심 보장 내용 및 특징 | 최적 적용 도메인 |
|:---|:---|:---|:---|
| Linearizability (선형성)| **Strong** | 완료된 연산의 실시간 순서를 보존 | **금융 계좌 잔액, 한정판 재고** |
| Sequential (순차) | 상 (Strong)| 모든 노드가 동일한 연산 순서로 관찰 (시간 불일치 허용)| 멀티플레이 게임 이벤트 |
| Causal (인과) | 중상 (Medium)| 인과 관계(질문-답변)가 있는 연산 간의 순서만 보장 | 게시글 댓글 및 대댓글 시스템 |
| Session (세션) | 중 (Medium)| **내가 쓴 데이터는 내가 즉시 최신으로 관찰 (RYW)** | **SNS 프로필 및 장바구니** |
| Eventual (최종) | **Weak** | 추가 쓰기가 없으면 궁극적으로 모든 복제본 수렴 | **SNS 타임라인 피드, 통계 캐시**|

#### 한줄 요약
- 금융·재고는 선형성(Linearizability), 사용자 경험은 세션(RYW), 대규모 조회는 최종 일관성을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Split-Brain**: 네트워크 분할로 인해 두 진영의 노드가 서로 리더라고 주장하며 독립 쓰기를 받아 데이터가 파괴되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 네트워크 분할의 Split-Brain 위험 | **Quorum·Fencing 기반 합의** 적용 | 소수 진영의 쓰기 차단 |
| 최종 일관성 DB에서 결제 직후 잔액이 안 바뀐 것처럼 보임 | **Read-Your-Writes 세션 일관성 및 마스터 노드 강제 읽기 라우팅** | 사용자 경험 및 신뢰성 확보 |
| 동시 주문의 재고 오버부킹 | **버전 조건부 갱신·재시도** 적용 | 경쟁 갱신의 충돌 감지 |
| 복제 지연의 Stale Read 노출 | 도메인별 **강한 읽기 옵션** 적용 | 오래된 읽기 위험 감소 |

#### 한줄 요약
- 네 대책은 필요한 구간에만 강한 일관성을 사서 쓰는 선택이며, 세션 보장이나 마스터 강제 읽기는 읽기 부하를 분산해 얻던 이득을 정합성과 맞바꾼다.

## Ⅶ. 결론

- 잔액·재고는 **선형성**, 피드·캐시는 **최종 일관성** 선택

#### 한줄 요약
- 사용자 직후 읽기는 RYW로 보완하고 허용 지연을 명시한다.
