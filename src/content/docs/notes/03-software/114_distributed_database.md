## 미리 알고가기

- **분산 데이터베이스(Distributed Database)**: 여러 노드의 분할·복제 데이터를 하나의 논리 데이터베이스로 제공하는 구조임
- **파티셔닝(Partitioning)**: 서로 다른 데이터를 키나 범위에 따라 여러 노드에 나누는 방식임
- **복제(Replication)**: 같은 데이터의 사본을 여러 노드나 장애 영역에 유지하는 기술임
- **분산 투명성(Distribution Transparency)**: 데이터 위치·분할·복제 세부를 응용 질의에서 숨기는 성질임
- **2단계 커밋(Two-phase Commit, 2PC)**: 준비와 결정 두 단계로 참여 노드의 커밋·중단을 하나의 결과로 조정하는 프로토콜임
- **합의 프로토콜(Consensus Protocol)**: 분산 노드가 로그 순서·리더·확정 지점에 같은 결정을 내리게 하는 규칙임
- **정족수(Quorum)**: 읽기·쓰기 완료에 필요한 복제본 응답 수를 뜻함
- **파티션 맵(Partition Map)**: 키 범위와 이를 담당하는 노드·복제본의 위치를 연결한 정보임
- **분산 실행기(Distributed Executor)**: 여러 파티션에 연산을 보내고 중간 결과를 병합하는 구성요소임
- **재분산(Rebalancing)**: 노드 추가·제거 또는 편중에 맞춰 파티션을 다시 배치하는 작업임
- **테넌트(Tenant)**: 하나의 공유 시스템을 독립적으로 사용하는 고객이나 조직 단위임
- **교차 파티션 트랜잭션(Cross-partition Transaction)**: 둘 이상의 파티션 데이터를 한 논리 거래로 변경하는 작업임

## Ⅰ. 개요

- 정의/개념: 분할·복제 데이터를 하나의 DB처럼 제공함
- **배경/필요성**: 단일 노드 확장·장애 한계로 분산 저장 필요

### 쉽게 이해하기 (학습용)
- 장부를 지점에 나누고 사본과 합의 규칙으로 하나처럼 쓰는 데이터베이스임

## Ⅱ. 특징

- 재분산으로 노드 추가 시 용량과 처리량을 확장한다.
- 정족수·리더 전환으로 노드 장애에도 요청을 처리한다.
- 분산 투명성으로 응용이 논리 질의를 사용한다.
- 네트워크 단절·복제 지연·교차 거래 비용이 늘어난다.

### 쉽게 이해하기 (학습용)
- 수평 확장과 장애 대응은 좋아지지만 네트워크와 사본 비용이 추가됨

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 파티션 맵·라우터 | 범위를 노드에 연결하고 질의를 대상 파티션으로 전달함 |
| 분산 실행기 | 여러 파티션의 연산을 계획하고 중간 결과를 병합함 |
| 복제 로그·합의 | 복제본 변경 순서와 리더·커밋 지점을 일치시킴 |
| 분산 트랜잭션 | 여러 파티션의 준비·커밋·중단을 하나의 결과로 조정함 |
| 장애 감지·복구 | 노드를 판정하고 복제본 보충과 파티션 재분산을 수행함 |

```text
  질의전달
      ↓
  결과병합
      ↓
  합의복제
      ↓
  결과조정
      ↓
  장애복구
```

> 요약: 라우팅·복제 합의·트랜잭션으로 변경 조정

### 쉽게 이해하기 (학습용)
- 지점 안내와 실행기 및 사본 합의와 분산 거래 조정기로 구성됨

## Ⅳ. 원리 및 절차 흐름도

```text
  요청수신
      ↓
  파티션선택
      ↓
  복제본처리
      ↓
  커밋판정
      ↓
  결과병합
```

| 절차 | 설명 |
|:---|:---|
| **요청 수신** | 라우터가 질의와 일관성 및 트랜잭션 정보를 수신함 |
| **파티션 선택** | 파티션 맵에서 대상 노드와 복제본 집합을 결정함 |
| **복제본 처리** | 대상 복제본이 읽기 또는 로그 기반 쓰기를 수행함 |
| **일관성·커밋 판정** | 정족수나 분산 커밋 조건을 충족했는지 확인함 |
| **결과 병합** | 분산 실행기가 파티션별 결과를 정렬하고 집계해 반환함 |

> 요약: 복제본 처리·커밋 확인·결과 병합

### 쉽게 이해하기 (학습용)
- 담당 지점을 찾고 사본 확인과 지점 커밋을 거쳐 결과를 합침

## Ⅴ. 종류 및 비교

| 판단 기준 | 분산 데이터베이스 | 단일 데이터베이스 |
|:---|:---|:---|
| 핵심 특징 | 파티션과 복제본을 여러 노드에 배치함 | 한 인스턴스의 저장 구조를 중심으로 배치함 |
| 확장 방식 | 노드 추가와 파티션 재분산 | 인스턴스와 저장소 증설 |
| 트랜잭션·일관성 | 합의와 분산 커밋으로 노드 변경을 통제함 | 단일 로그·잠금·격리 수준으로 통제함 |
| 적용 기준 | 수평 확장과 장애 영역 분산 | 단순한 거래 경계와 운영 |
| 주요 위험 | 네트워크 분할·합의 지연·운영 복잡도 | 단일 장애점·확장 한계 |

> 요약: 단일은 한 경로, 분산은 라우팅·복제 합의

### 쉽게 이해하기 (학습용)
- 단일은 한 지점이고 분산은 여러 지점의 확장과 거래를 관리함

## Ⅵ. 실무 사례

1. 테넌트 DB는 파티셔닝을 하고 점유율과 재분산 시간을 확인함

### 쉽게 이해하기 (학습용)
- 테넌트 키로 분산한 뒤 노드별 점유율과 재분산 시간을 측정하면 확장 시 운영 비용을 예측할 수 있음

## Ⅶ. 결론

- 파티션·복제·거래 경계·복구 비용 함께 설계

### 쉽게 이해하기 (학습용)
- 분산 데이터베이스는 교차 거래·합의 지연·복구 시간을 측정해 도입함
