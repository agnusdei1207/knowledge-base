## 미리 알고가기

- **공유 책임 모델**: 클라우드 공급자와 소비자가 보안·운영·규정 준수 책임을 나누는 기준이다
- **공급자**: 데이터센터·물리 장비·기반 네트워크 등 클라우드 자체의 보안을 담당한다
- **소비자**: 계정·데이터·애플리케이션과 선택한 서비스의 구성 보안을 담당한다
- **책임 경계**: 서비스형 인프라에서는 사용자가 더 많이 관리하고 서비스형 소프트웨어에서는 공급자가 더 많이 관리한다
- **통제 상속**: 공급자가 수행한 물리·플랫폼 통제의 감사 증적을 소비자가 활용하는 방식이다
- **책임 매트릭스**: 통제 항목별 수행·승인·증적 보유 주체를 명시한다
- **서비스형 인프라(Infrastructure as a Service, IaaS)**: ‘아이에이에스’로 읽고 영문 핵심어의 머리글자를 딴 표기이며 소비자가 운영체제부터 관리하는 클라우드 모델이다
- **서비스형 플랫폼(Platform as a Service, PaaS)**: ‘파스’로 읽고 영문 핵심어의 머리글자를 딴 표기이며 공급자가 실행 플랫폼까지 관리하는 클라우드 모델이다
- **서비스형 소프트웨어(Software as a Service, SaaS)**: ‘사스’로 읽고 영문 핵심어의 머리글자를 딴 표기이며 공급자가 완성형 애플리케이션까지 제공하는 모델이다
- **운영체제(Operating System, OS)·런타임**: ‘오에스’는 두 영문 단어의 머리글자를 딴 표기이며 운영체제는 하드웨어 자원을 관리하고 런타임은 애플리케이션 실행 환경을 제공한다
- **정책 코드**: 허용 구성과 위반 조건을 자동 검사 가능한 코드로 표현한 규칙이다
- **감사 증적**: 통제가 실제 수행됐음을 보여주는 보고서·로그·설정 이력이다
- **휴면 계정**: 정한 기간 동안 사용되지 않아 회수·차단 검토가 필요한 계정이다

## Ⅰ. 개요

- **정의/개념**: 서비스 모델에 따라 보안 의무를 분담하는 규약이다
- **배경/필요성**: 서비스 사용 뒤에도 책임이 남아 경계 명시 필요

### 쉽게 이해하기 (학습용)
- 클라우드를 써도 데이터·계정 책임은 남으므로 분담표가 필요하다

## Ⅱ. 특징

- 공급자는 인프라, 소비자는 구성을 통제한다
- 상위 모델도 데이터·접근 책임은 소비자에게 남는다
- 서비스 모델별 관리 계층이 책임 경계를 바꾼다
- 통제 상속은 중복 감사를 줄이고 증적을 요구한다

### 쉽게 이해하기 (학습용)
- 지키는 기반과 소비자의 계정 설정을 연결해야 한다

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    A[서비스 계층 목록] --> B[책임 문서·통제 목록]
    B --> C[책임 매트릭스]
    C --> D[구성 정책]
    D --> E[감사 증적 저장소]
```

| 설계 요소 | 설명 |
|:---|:---|
| 서비스 계층 목록 | 물리·가상화·OS·런타임·앱·데이터 범위를 식별함 |
| 책임 문서·통제 목록 | 공급자 범위와 소비자의 계정과 패치 항목을 명시함 |
| 책임 매트릭스 | 통제별 수행자·승인자·증적 보유자를 연결함 |
| 구성 정책 | 허용 설정과 위반 조건을 정책 코드로 검사함 |
| 감사 증적 저장소 | 보고서·로그·설정 이력을 보관함 |

> 요약: 매트릭스가 공급자 증적과 소비자 설정을 연결한다

### 쉽게 이해하기 (학습용)
- 공급자 보고서와 로그를 묶어 책임 이행을 증명한다

## Ⅳ. 원리 및 절차 흐름도

| 절차 | 설명 |
|:---|:---|
| **범위확인** | 공급자가 운영하는 책임 계층을 확인함 |
| **통제분해** | 패치와 로그 통제를 세부 항목으로 나눔 |
| **책임배정** | 수행자와 승인자 역할을 매트릭스에 배정함 |
| **증적연결** | 감사 자료와 소비자 설정 및 로그를 연결함 |
| **정기검증** | 서비스 변경 시 책임표와 운영을 갱신함 |

> 요약: 계층을 통제로 분해해 책임자와 증적을 갱신한다

### 쉽게 이해하기 (학습용)
- 보안 일을 나누고 담당자와 확인 자료를 점검한다

## Ⅴ. 종류 및 비교

| 판단 기준 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|
| 핵심 특징 | 소비자가 OS부터 운영함 | 공급자가 런타임까지 운영함 | 공급자가 애플리케이션까지 운영함 |
| 적용 기준 | 광범위한 보안 통제권을 확보하고자 할 때 | 인프라 보안은 위임하고 앱에 집중할 때 | 데이터 보호와 접근 관리 위주로 수행할 때 |
| 주요 위험 | OS·네트워크 구성 오류 | 런타임·계정 설정 오류 | 데이터·권한 설정 오류 |

> 요약: 관리 계층이 늘어도 권한과 보존은 소비자가 책임짐

### 쉽게 이해하기 (학습용)
- 서비스를 사용해도 계정과 공개 범위를 정할 책임은 남는다.

## Ⅵ. 실무 사례

1. IaaS는 운영체제를 패치하고 미패치 인스턴스를 확인한다
2. SaaS는 공유 권한을 정리하고 휴면 계정 수를 확인한다

### 쉽게 이해하기 (학습용)
- IaaS는 소비자가 OS 패치 누락을 찾아야 한다
- SaaS는 소비자가 공개 권한과 휴면 계정을 줄인다

## Ⅶ. 결론

- 공급자 증적과 소비자 설정이 모두 있을 때 통과한다

### 쉽게 이해하기 (학습용)
- 기반을 맡겨도 데이터·계정 책임은 소비자에게 남는다
