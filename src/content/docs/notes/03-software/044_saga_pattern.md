## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **사가 패턴(Saga Pattern)**: 여러 서비스의 로컬 트랜잭션을 순차 실행하고 실패 시 완료 작업을 보상하는 분산 트랜잭션 패턴이다.
- **2단계 커밋(Two-Phase Commit, 2PC)**: 참여자의 준비 동의를 모은 뒤 중앙 조정자가 전체 커밋 또는 중단을 결정하는 방식이다.
- **전역 잠금(Global Lock)**: 여러 참여자의 자원을 커밋 결정까지 함께 묶어 두는 잠금이다.

</details>

- 정의/개념: **사가 패턴** 은 여러 서비스의 로컬 트랜잭션을 순차 실행하고 중간 실패 시 완료된 작업의 효과를 보상하는 **분산 트랜잭션 패턴**
- 배경/필요성: **2PC 전역 잠금** 으로 독립 서비스의 가용성•자율성 제약

#### 한줄 요약

- 로컬 커밋 연결과 역순 보상 기반 **분산 일관성**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **로컬 트랜잭션(Local Transaction)**: 한 서비스가 소유한 저장소 안에서만 원자적으로 커밋하는 작업이다.
- **보상 트랜잭션(Compensating Transaction)**: 과거 커밋을 지우지 않고 반대 업무를 새로 커밋해 효과를 상쇄하는 처리다.
- **중간 상태**: Saga의 일부 로컬 작업만 커밋되어 다른 서비스에 진행 결과가 노출된 상태다.

</details>

- **로컬 커밋 연결** 로 전역 잠금 회피
- **보상 트랜잭션** 으로 완료 단계의 효과를 역순 상쇄
- **중간 상태 노출** 을 허용하며 업무 일관성 회복

#### 한줄 요약

- 전역 잠금 회피와 **중간 상태•보상 복잡도** 절충

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **흐름 제어기(Workflow Controller)**: 단계 결과와 Saga 상태를 읽어 다음 작업이나 역순 보상을 선택하는 구성요소다.
- **메시지 채널(Message Channel)**: 서비스 간 명령과 이벤트를 전달하는 통로다.
- **재전송(Redelivery)**: 응답 누락 시 같은 메시지를 다시 보내는 처리다.
- **Saga 상태 저장소**: 각 단계의 완료•실패•보상 여부와 재시도 이력을 영구 기록해 중단 뒤 흐름을 재개하게 하는 저장소다.

</details>

```text
[Saga 상태 저장소]
         |
         |
[흐름 제어기] -------- [메시지 채널] -------- [참여 서비스•로컬 저장소]
```

선의 의미: 흐름 제어기와 Saga 상태 저장소의 선은 완료•실패•보상 상태의 기록과 참조 관계, 흐름 제어기와 메시지 채널의 선은 작업•보상 명령과 결과 이벤트의 교환 관계, 메시지 채널과 참여 서비스•로컬 저장소의 선은 로컬•보상 트랜잭션 요청 전달 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 흐름 제어기 | **다음 작업•역순 보상** 선택 |
| Saga 상태 저장소 | **완료•실패•보상 상태** 기록 |
| 메시지 채널 | **명령•이벤트 전달•재전송** |
| 참여 서비스•로컬 저장소 | **로컬•보상 트랜잭션** 커밋 |

#### 한줄 요약

- 흐름 제어•상태 저장•메시지•**참여 서비스 구조**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **로컬 트랜잭션 실행**: 현재 단계의 참여 서비스가 자기 저장소에 업무 변경을 커밋하는 동작이다.
- **단계 결과•상태 기록**: 로컬 작업의 성공•실패와 완료 범위를 Saga 상태 저장소에 남기는 동작이다.
- **다음 단계 판정**: 남은 작업의 실행, 전체 완료 또는 보상 진입을 선택하는 동작이다.
- **역순 보상 범위 확정**: 실패 전에 완료된 단계 중 상쇄할 작업을 반대 순서로 정하는 동작이다.
- **보상 트랜잭션 실행**: 정해진 보상 작업을 새 로컬 커밋으로 수행해 기존 효과를 상쇄하는 동작이다.

</details>

```text
[Saga 업무 요청]
       |
       v
+--------------------------+
| 1. 로컬 트랜잭션 실행    |<------------------+
+--------------------------+                   |
       |                                        |
       v                                        |
+--------------------------+                   |
| 2. 단계 결과•상태 기록   |                   |
+--------------------------+                   |
       |                                        |
       v                                        |
+--------------------------+     남은 단계 있음 |
| 3. 다음 단계 판정        |-------------------+
+--------------------------+
       | 전체 완료                 | 실패
       v                           v
 [Saga 완료]              +--------------------------+
                          | 4. 역순 보상 범위 확정   |
                          +--------------------------+
                                      |
                                      v
                          +--------------------------+
                          | 5. 보상 트랜잭션 실행    |---- 실패 ----> [재시도•수동 복구]
                          +--------------------------+
                                      |
                                    완료
                                      v
                          [업무 실패•일관성 회복]
```

**동작 원리**

1. **로컬 트랜잭션 실행**: 현재 단계의 업무 변경 커밋
2. **단계 결과•상태 기록**: 성공•실패와 완료 범위 저장
3. **다음 단계 판정**: 후속 실행•완료•보상 진입 선택
4. **역순 보상 범위 확정**: 완료 작업의 반대 순서 결정
5. **보상 트랜잭션 실행**: 새 커밋으로 기존 효과 상쇄

#### 한줄 요약

- 단계 실패 시 완료 작업의 **역순 보상 흐름**

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **오케스트레이션(Orchestration)**: 중앙 조정자가 다음 작업과 실패 시 보상 순서를 명령하는 Saga 제어 방식이다.
- **코레오그래피(Choreography)**: 각 서비스가 앞 단계 이벤트에 반응해 다음 작업이나 보상을 실행하는 Saga 제어 방식이다.
- **순환 의존**: 서비스 이벤트가 서로를 다시 호출해 제어 흐름이 고리처럼 얽히는 관계다.

</details>

| Saga 제어 방식 | 오케스트레이션 | 코레오그래피 |
|:---|:---|:---|
| 적용 기준 | **분기•보상 규칙** 이 많을 때 | 짧은 **선형 이벤트 흐름** |
| 핵심 특징 | **중앙 조정자** 가 명령•상태 관리 | 서비스가 **이벤트** 에 반응 |
| 한계 | **조정자 장애•의존 집중** | **순환 의존•흐름 추적 난도** |

> 요약: 복잡한 보상은 **중앙 조정**, 단순 흐름은 **이벤트 연쇄**

#### 한줄 요약

- 복잡한 분기는 오케스트레이션, 단순 연쇄는 **코레오그래피**

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **트랜잭셔널 아웃박스(Transactional Outbox)**: 로컬 업무 변경과 보낼 메시지를 한 트랜잭션에 저장한 뒤 전달하는 방식이다.
- **멱등키(Idempotency Key)**: 같은 요청의 재전송을 식별해 업무 효과를 한 번만 반영하게 하는 고유 값이다.
- **멱등성(Idempotency)**: 같은 메시지를 반복 처리해도 한 번 처리한 것과 같은 업무 상태를 유지하는 성질이다.
- **대사(Reconciliation)**: 여러 서비스 상태를 비교해 누락•불일치•미완료 보상을 찾아 정정하는 절차다.
- **수동 복구(Manual Recovery)**: 자동 보상으로 풀지 못한 상태를 담당자가 업무 규칙에 맞게 정정하는 절차다.
- **업무 식별자(Business Identifier)**: 하나의 Saga와 중복 요청을 구분하는 고유 값이다.
- **처리 이력(Processing History)**: 이미 반영한 명령과 이벤트 기록이다.
- **재시도 상한(Retry Limit)**: 자동 보상을 다시 시도할 최대 횟수다.
- **수동 복구 큐(Manual Recovery Queue)**: 재시도 한도를 넘은 Saga를 담당자에게 전달하는 대기열이다.
- **진행 상태(In-progress State)**: Saga가 아직 완료되지 않았음을 나타내는 상태다.
- **후속 작업 제한(Follow-up Restriction)**: 확정 상태가 필요한 다음 업무를 막는 통제다.
- **복잡도 임계값(Complexity Threshold)**: 분기•보상•이벤트 의존이 어느 수준을 넘으면 중앙 오케스트레이션으로 전환할지 정한 기준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 로컬 커밋 후 메시지 발행 실패 | **트랜잭셔널 아웃박스** 로 상태•메시지 원자 저장 | **단계 누락** 방지 |
| 명령•이벤트 재전송으로 중복 결제•보상 | **업무 식별자•멱등키•처리 이력** 저장 | **중복 부작용** 방지 |
| 보상 실패로 중간 상태가 장기간 지속 | **재시도 상한•대사•수동 복구 큐** | **미완료 Saga** 회수 |
| 진행 중 중간 상태를 완료 상태로 오인 | **진행 상태 표시•후속 작업 제한** | **업무 일관성 오인** 방지 |
| 코레오그래피 이벤트가 순환 의존으로 확장 | 복잡도 임계 시 **오케스트레이션 전환** | **제어 흐름 추적성** 확보 |

#### 한줄 요약

- 아웃박스•멱등성•대사•**수동 복구** 통제

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **보상 가능성**: 이미 커밋한 업무 효과를 반대 업무로 안전하게 상쇄할 수 있는 성질이다.
- **Saga 적용 조건**: 보상 트랜잭션을 정의할 수 있고 진행 중 중간 상태를 업무가 허용하는 조건이다.

</details>

- **보상 트랜잭션** 이 가능하고 중간 상태를 허용하는 업무에만 **Saga** 적용

#### 한줄 요약

- 보상 가능하고 중간 상태를 허용할 때 **Saga 적용**
