## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **사가 패턴(Saga Pattern)**: 각 마이크로서비스의 독립된 데이터베이스 환경에서 전역 분산 락(2PC) 없이, 일련의 로컬 트랜잭션을 순차 실행하고 실패 시 역순으로 보상 트랜잭션을 실행하여 데이터 일관성을 맞추는 분산 트랜잭션 관리 패턴.
- **보상 트랜잭션(Compensating Transaction)**: 이미 커밋된 이전 단계의 로컬 트랜잭션 변경 사항을 비즈니스적으로 취소하거나 상쇄(Undo)하기 위해 실행하는 반대 작업.
- **2단계 커밋(Two-Phase Commit, 2PC)**: 모든 분산 데이터베이스 노드가 커밋 준비를 완료할 때까지 전역 락을 유지하여 원자성을 보장하는 동기식 분산 트랜잭션 프로토콜.

</details>

- 정의/개념: 분산 환경에서 전역 잠금 대신 **로컬 트랜잭션**의 순차 커밋과 실패 시 **보상 트랜잭션(Compensating Transaction)** 을 통해 **최종 일관성(Eventual Consistency)** 을 달성하는 트랜잭션 관리 패턴
- 배경/필요성: 서비스별 독립 DB 환경(Database-per-Service)에서 전통적 2PC 적용 시 발생하는 블로킹 지연, 가용성 저하 및 단일 장애점(SPOF) 문제 해소 요구

#### 한줄 요약
- 분산 서비스 간에 로컬 트랜잭션을 순차 실행하고, 실패 시 역순 보상 트랜잭션으로 일관성을 회복한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **코레오그래피(Choreography)**: 중앙 조정자 없이 각 서비스가 도메인 이벤트를 발행 및 구독하여 다음 단계의 로컬 트랜잭션을 자율적으로 트리거하는 분산 방식.
- **오케스트레이션(Orchestration)**: 중앙의 사가 오케스트레이터가 전체 워크플로우의 실행 순서와 실패 시 보상 트랜잭션 호출을 직접 통제하는 중앙 집중 방식.

</details>

- 2PC 전역 락(Global Lock) 배제를 통한 높은 시스템 처리량과 무차단 비동기 실행 지원
- 자율적인 **코레오그래피(Choreography)** 방식과 중앙 통제형 **오케스트레이션(Orchestration)** 구현 방식 제공
- 중간 단계 커밋으로 인한 **격리성(Isolation) 부재(ACD 보장)** 및 비동기 수렴을 통한 **최종 일관성(Eventual Consistency)** 수용

#### 한줄 요약
- 전역 잠금 없는 고성능 분산 처리를 지원하며, 코레오그래피와 오케스트레이션 방식으로 구현된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사가 오케스트레이터(Saga Orchestrator)**: 트랜잭션 워크플로우의 상태 머신(State Machine)을 영속화하고 단계별 명령(Command) 전달 및 보상 흐름을 지휘하는 전용 관리 컴포넌트.
- **시맨틱 락(Semantic Lock)**: 격리성 부재로 인한 Dirty Read를 방지하기 위해 데이터 레코드에 `PENDING` 등 상태 플래그를 설정하여 타 프로세스의 변경을 방어하는 애플리케이션 수준 락.

</details>

```text
[ Saga Orchestration 아키텍처 ]

                      [ 사가 상태 저장소 (State Store) ]
                                     │
                      [ 사가 오케스트레이터 (Orchestrator) ]
                         │                     │
      (명령 / 이벤트 응답)│                     │(명령 / 이벤트 응답)
                         ▼                     ▼
                 [ 주문 서비스 ]         [ 결제 서비스 ]
                   (로컬 주문 DB)          (로컬 결제 DB)
```

선의 의미: 오케스트레이터가 상태 저장소를 기반으로 각 서비스에 로컬 트랜잭션 실행 및 보상 명령을 전달하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **사가 오케스트레이터** | 워크플로우 상태 관리, 다음 단계 서비스 호출 및 실패 시 역순 보상 지시 |
| **사가 상태 저장소** | 분산 트랜잭션의 현재 진행 단계와 실패 이력을 원자적으로 기록 |
| **참여 서비스(Participants)** | 로컬 트랜잭션을 실행하고 결과를 이벤트로 반환하며 보상 요청 시 상쇄 작업 수행 |
| **메시지 브로커** | 서비스 간 명령 메시지와 응답 이벤트의 신뢰성 있는 비동기 전달 보장 |

#### 한줄 요약
- 오케스트레이터가 상태 머신을 기반으로 각 참여 서비스에 로컬 커밋 및 보상 명령을 순차적으로 전달한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **피벗 트랜잭션(Pivot Transaction)**: 사가 흐름에서 이 단계가 성공하면 이후 작업은 롤백 없이 반드시 완료(Go-Forward)되는 전환점 트랜잭션.

</details>

```text
정방향 실행 흐름:
1. 주문 생성(로컬 커밋) ──▶ 2. 결제 승인(로컬 커밋) ──▶ 3. 재고 차감 시도(실패 발생)
                                                              │
역방향 보상 흐름:                                             ▼
5. 주문 취소(보상 트랜잭션) ◀── 4. 결제 취소/환불(보상 트랜잭션) ┘
```

**동작 원리**

1. **정방향 로컬 트랜잭션**: 주문 서비스가 주문 레코드를 생성하고 로컬 DB에 커밋
2. **후속 단계 트리거**: 결제 서비스가 결제 승인을 처리하고 로컬 DB에 커밋
3. **오류 발생 식별**: 재고 서비스에서 재고 부족으로 트랜잭션 실패 이벤트 발생
4. **역방향 보상 개시**: 결제 서비스로 보상 명령을 전송하여 결제 취소(환불) 로컬 트랜잭션 커밋
5. **최종 상태 수습**: 주문 서비스로 보상 명령을 전송하여 주문 상태를 취소로 변경하고 일관성 수렴

#### 한줄 요약
- 정방향 로컬 트랜잭션을 순차 실행하다가 실패 발생 시 역방향 보상 트랜잭션으로 상태를 정합화한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **트랜잭셔널 아웃박스(Transactional Outbox)**: 데이터베이스 갱신과 메시지 발행의 원자성을 보장하기 위해 아웃박스 테이블을 거쳐 브로커로 전달하는 신뢰성 패턴.

</details>

| 비교 항목 | 코레오그래피 (Choreography) | 오케스트레이션 (Orchestration) | 2단계 커밋 (2PC) |
|:---|:---|:---|:---|
| **적용 기준** | 2~4개 이하의 단순 서비스 간 트랜잭션 | 5개 이상의 복잡한 단계 및 감사 추적 필요 시 | 단일 도메인 내 엄격한 ACID 원자성 필수 시 |
| **제어 메커니즘** | 이벤트 발행/구독 기반 분산 자율 제어 | 중앙 오케스트레이터의 명시적 명령/응답 | 분산 코디네이터 기반 전역 락(Global Lock) |
| **결합도 및 추적성** | 느슨한 결합도 / 흐름 추적 및 디버깅 복잡 | 중앙화된 로직 / 워크플로우 가시성 및 추적 용이 | 높은 결합도 / 코디네이터 단일 장애 취약 |
| **성능 및 확장성** | 고성능, 비동기 이벤트 기반 수평 확장 | 오케스트레이터 상태 저장 오버헤드 존재 | 전역 잠금 대기로 인한 성능 및 확장성 저하 |

#### 한줄 요약
- 단순 흐름에는 자율적인 코레오그래피를, 복잡한 비즈니스에는 중앙 통제형 오케스트레이션을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **멱등성(Idempotency)**: 동일한 보상 트랜잭션 메시지가 네트워크 오류로 여러 번 재전송되어도 최초 1회만 처리되고 동일한 결과를 보장하는 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중간 커밋 상태 노출로 인한 Dirty Read (**격리성 부재**) | 상태 플래그(`PENDING`) 및 **시맨틱 락(Semantic Lock)** 적용 | 미완료 트랜잭션 데이터의 비정상적 변경 방지 |
| 보상 트랜잭션 실패로 인한 데이터 불일치 잔존 | 메시지 재시도(Retry) 정책 및 **데드 레터 큐(DLQ)** 모니터링 | 보상 작업의 궁극적 완료 보장 및 수동 정합 지원 |
| 네트워크 재전송으로 인한 중복 보상 실행 | **트랜잭셔널 아웃박스** 및 고유 트랜잭션 ID 기반 **멱등성(Idempotency)** 보장 | 중복 취소·환불로 인한 2차 결함 원천 방지 |

#### 한줄 요약
- 시맨틱 락으로 격리성을 보완하고, 멱등성 보장과 DLQ 재시도를 통해 보상 트랜잭션의 신뢰성을 확보한다.

## Ⅶ. 결론

- MSA 환경에서 분산 데이터 일관성 유지를 위해 **Saga 패턴**을 기본 아키텍처로 채택하되, 워크플로우 복잡도가 높은 핵심 비즈니스는 **오케스트레이터(Temporal/Step Functions)** 기반 상태 관리를 적용하고 멱등성과 시맨틱 락 설계를 병행하여 데이터 신뢰성을 보장

#### 한줄 요약
- 분산 서비스의 규모와 복잡도를 고려하여 코레오그래피 또는 오케스트레이션 사가 패턴을 선별 도입한다.
