## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **칸반(Kanban)**: 워크플로우를 보드에 시각화하고 진행 중 작업(WIP)을 엄격히 제한하여 지속적인 가치 흐름(Continuous Flow)을 달성하는 린(Lean) 기반 프레임워크.
- **WIP(Work In Progress)**: 착수되었으나 아직 완료(Done)되지 않은 공정 내의 모든 미완료 작업 카드.

</details>

- 정의/개념: 작업을 시각화하고 **WIP Limit(진행 중 작업 제한)** 을 적용한 **당김 방식(Pull System)** 으로 공정 병목을 해소하는 작업 흐름 관리 기법
- 배경/필요성: 동시 착수 작업의 과도한 밀어넣기(Push)로 인한 **잦은 문맥 전환, 대기열 정체 및 리드타임 지연 해결 불가**

#### 한줄 요약
- 작업 흐름을 시각화하고 WIP를 제한하여 지속적이고 안정적인 가치 흐름을 유지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **리틀의 법칙(Little's Law)**: 안정 상태의 시스템에서 $\text{Lead Time} = \frac{\text{WIP}}{\text{Throughput}}$이 성립하여, WIP를 줄이면 리드타임이 단축된다는 원리.
- **누적 흐름도(CFD: Cumulative Flow Diagram)**: 시간 경과에 따른 각 공정별 작업 누적량을 영역 차트로 나타내어 병목 구간을 시각화하는 도구.

</details>

- **WIP Limit** 적용을 통해 **리틀의 법칙(Little's Law)** 에 근거한 평균 리드타임 직접 단축
- 고정 타임박스(스프린트) 없이 작업 완료 즉시 배포하는 **연속적 가치 흐름(Continuous Flow)**
- **누적 흐름도(CFD)** 및 사이클 타임 메트릭 기반의 데이터 주도적 프로세스 개선

#### 한줄 요약
- 리틀의 법칙에 기반해 WIP를 제한하고 누적 흐름도(CFD)로 병목을 제거한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Pull System(당김 방식)**: 후속 공정에 여유 슬롯(WIP 한도 미만)이 생겼을 때만 선행 공정의 작업을 가져오는 메커니즘.

</details>

```text
[칸반 보드 및 WIP 제한 구조]
|-- 백로그 / 대기열 (Backlog: 우선순위 정렬된 요구사항)
|-- 분석/설계 단계 (WIP Limit: 2) -> 카드 2개 도달 시 신규 유입 차단
|-- 구현 단계 (WIP Limit: 3) -> 개발 진행 중
|-- 코드리뷰 / QA 검증 단계 (WIP Limit: 2)
`-- 배포 완료 (Done: 지속적 프로덕션 릴리즈)
```

선의 의미: 계층 및 Pull 기반 작업 흐름 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| 칸반 보드 (Board) | 워크플로우의 모든 단계와 작업 카드를 투명하게 시각화 |
| 작업 카드 (Card) | 요구사항 세부 명세, 담당자, 진입 일자 및 체류(Aging) 시간 표시 |
| WIP Limit 정책 | 각 공정 컬럼에 동시 체류 가능한 **최대 작업 카드 수**를 명시적으로 제한 |
| 흐름 메트릭 (Metrics) | 리드타임, 사이클타임, 처리량(Throughput) 및 **CFD 분석** 지표 산출 |

#### 한줄 요약
- 칸반 보드와 카드, 컬럼별 WIP 제한 정책, 흐름 분석 메트릭으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **긴급 트랙(Expedite Lane)**: 중대한 장애나 보안 취약점 등 긴급 조치가 필요할 때 일반 WIP 제한을 예외적으로 우회하는 패스트트랙.

</details>

```text
하류 공정 작업 완료로 해당 컬럼에 가용 슬롯 발생
        │
   컬럼별 WIP 제한 확인 (현재 작업 수 < WIP Limit)
        │
   상류 공정에서 최상위 우선순위 카드를 당겨옴 (Pull)
        │
   작업 수행 및 실시간 병목/노화(Aging) 모니터링
        │
   작업 완료 후 다음 공정으로 이동 및 누적 흐름도(CFD) 지표 갱신
```

#### 한줄 요약
- 하류 여유 슬롯 확인 → 상류 작업 당김(Pull) → 작업 수행 및 노화 감시 → 완료 및 지표 갱신 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **스크럼반(Scrumban)**: 스크럼의 정기 이벤트(회고)와 칸반의 WIP 제한 및 흐름 시각화를 융합한 하이브리드 모델.

</details>

| 비교 항목 | 칸반 (Kanban) | 스크럼 (Scrum) | 스크럼반 (Scrumban) |
|:---|:---|:---|:---|
| 실행 단위 | **연속적 단일 흐름 (Continuous Flow)** | **고정 타임박스 스프린트 (1~4주)** | 유연한 이터레이션 결합 |
| 핵심 제약 | **컬럼별 WIP Limit 제한** | 스프린트 백로그 범위 동결 | 버퍼 크기 기반 동적 조절 |
| 역할 규정 | 특정 역할 없음 (기존 조직 유지) | PO, SM, Developers 엄격 규정 | 유연한 역할 정의 |
| 주 적용처 | **IT 운영, 장애 대응, 헬프데스크** | 신규 프로덕트 개발 | 개발과 운영이 혼재된 복합팀 |

#### 한줄 요약
- 지속적 운영 유지보수는 칸반, 계획 중심 신규 개발은 스크럼, 복합 환경은 스크럼반을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **작업 노화(Work Item Aging)**: 특정 카드가 특정 컬럼에서 예상 시간 이상 정체되어 전체 리드타임을 악화시키는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 상위 부서의 무분별한 작업 밀어넣기(Push) | **WIP Limit 엄격 준수** 및 용량 초과 시 신규 착수 차단 | 문맥 전환 제거 및 작업 완료율(Throughput) 40% 향상 |
| 특정 컬럼 내 작업 정체 및 **작업 노화(Work Item Aging)** | 일일 스탠드업 시 정체 카드 대상 **스워밍(Swarming: 전원 집중 협업)** | 병목 즉시 해소 및 리드타임 지연 예방 |
| 긴급 트랙(Expedite Lane) 남용으로 일반 작업 기아 | 전사 긴급 트랙 슬롯을 **최대 1개로 엄격 제한** | 우선순위 왜곡 방지 및 표준 작업 흐름 안정화 |
| 팀원들의 멀티태스킹으로 인한 효율 저하 | **인당 WIP 제한(Personal WIP: 1~2개)** 설정 | 집중도 극대화 및 개별 작업 품질 보장 |

#### 한줄 요약
- WIP 제한 준수, 스워밍 집중 협업, 긴급 트랙 1개 제한, 인당 WIP 통제로 흐름을 최적화한다.

## Ⅶ. 결론

- 운영 유지보수는 **칸반**, 리드타임 단축은 **WIP 제한** 선택

#### 한줄 요약
- 칸반은 시각화와 WIP 제한을 통해 공정의 병목을 실시간 제거하고 가치 흐름을 극대화하는 린 프레임워크다.
