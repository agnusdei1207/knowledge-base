## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **칸반(Kanban)**: 작업 항목을 보드에 시각화하고 진행 중 작업(WIP)을 제한하여 지속적인 가치 흐름(Continuous Flow)을 달성하는 린(Lean) 기반 애자일 프레임워크.
- **재공품/진행 중 작업(Work In Progress, WIP)**: 작업이 착수되었으나 아직 완료(Done) 단계에 도달하지 않은 대기열 내의 모든 작업 항목.
- **당김 방식(Pull System)**: 하류 공정에서 가용 처리 용량이 발생했을 때만 상류 공정으로부터 작업을 인입하여 병목과 대기 시간을 제어하는 프로세스 운영 방식.

</details>

- 정의/개념: 작업을 시각화하고 **WIP Limit(진행 중 작업 제한)** 을 적용한 **당김 방식(Pull System)** 으로 프로세스 병목을 해소하고 리드타임을 단축하는 작업 흐름 관리 기법
- 배경/필요성: 동시 착수 작업의 과도한 누적으로 인한 빈번한 컨텍스트 스위칭, 대기열 지연 및 완료율 저하 문제 해결 요구

#### 한줄 요약
- 작업 상태를 시각화하고 동시 진행 작업 수를 제한하여 지속적이고 안정적인 가치 흐름을 유지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **리틀의 법칙(Little's Law)**: 안정 상태의 대기열 시스템에서 평균 리드타임($W$)은 시스템 내 평균 진행 중 작업 수($L$)를 평균 처리율($\lambda$)로 나눈 값과 같다는 대기행렬 이론 ($\text{Lead Time} = \frac{\text{WIP}}{\text{Throughput}}$).
- **누적 흐름도(Cumulative Flow Diagram, CFD)**: 시간 경과에 따른 각 작업 단계별 누적 카드 수를 영역 차트로 표시하여 단계별 병목과 리드타임 변화를 시각화하는 지표 도구.

</details>

![리틀의 법칙에 따른 WIP와 평균 리드타임 관계](/study/diagrams/little-law-wip-lead-time.svg)

> 처리율을 하루 2건으로 고정한 파란 선은 WIP가 10건이면 평균 리드타임이 5일이 되는 리틀의 법칙 예시이며, 안정적인 유입•처리율을 가정한다.

- **WIP Limit** 적용을 통해 **리틀의 법칙(Little's Law)** 에 근거한 평균 리드타임 직접 단축
- 고정 타임박스(스프린트) 없이 작업 단위별 배포가 가능한 **연속적 가치 흐름(Continuous Flow)** 지원
- **누적 흐름도(CFD)** 및 리드타임/사이클타임 메트릭 기반의 데이터 중심 프로세스 지속 개선

#### 한줄 요약
- 리틀의 법칙에 기반하여 WIP를 제한하고 누적 흐름도로 병목을 식별하여 공정 효율을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **칸반 보드(Kanban Board)**: 워크플로우의 각 단계(To Do, In Progress, Review, Done)를 컬럼으로 구분하여 작업 카드의 위치를 표시하는 시각화 도구.
- **서비스 수준 기대치(Service Level Expectation, SLE)**: 특정 작업 항목이 착수된 후 완료되기까지 걸리는 시간에 대한 확률적 목표 기준.

</details>

```text
[ 백로그 ] ──────▶ [ 분석/설계 (WIP: 2) ] ──(Pull)──▶ [ 구현/검증 (WIP: 3) ] ──────▶ [ 완료 (Done) ]
  (대기)            [ 작업 카드 1 ]                      [ 작업 카드 3 ]
                    [ 작업 카드 2 ] (한도 도달)          [ 작업 카드 4 ] (1 슬롯 여유)
```

선의 의미: 컬럼 간 화살표는 하류 공정 여유 용량 발생 시 상류 카드를 인입하는 Pull 흐름

| 구성요소 | 책임 |
|:---|:---|
| **칸반 보드(Board)** | 작업 흐름의 각 단계와 정책을 한눈에 식별 가능하도록 전사 투명성 제공 |
| **작업 카드(Card)** | 요구사항 세부 명세, 담당자, 진입 일자 및 작업 노화(Aging) 시간 표시 |
| **WIP 제한 정책** | 각 공정 컬럼에 동시 체류 가능한 최대 작업 카드 수를 명시적으로 규정 |
| **흐름 지표(Metrics)** | 리드타임, 사이클타임, 처리량(Throughput) 및 CFD 분석 데이터 제공 |

#### 한줄 요약
- 칸반 보드와 카드로 작업 흐름을 시각화하고 컬럼별 WIP 한도로 과도한 유입을 차단한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **긴급 트랙(Expedite Lane)**: 중대한 시스템 장애나 보안 결함 등 최우선 처리가 필요한 긴급 작업에 한해 일반 WIP 제한을 예외 적용하는 전용 통로.

</details>

```text
1. 하류 공정 작업 완료 및 여유 슬롯 발생
            │
            ▼
2. 컬럼별 WIP 제한 확인: 해당 단계의 현재 WIP 수가 한도 미만인지 검증
            │
            ▼
3. 상류 공정 카드 당김(Pull): 우선순위가 가장 높은 대기 카드를 작업 단계로 인입
            │
            ▼
4. 작업 수행 및 병목 모니터링: 작업 노화 시간 추적 및 장애 발생 시 협업 해소
            │
            ▼
5. 작업 완료 및 흐름 지표 갱신: 리드타임 측정 및 누적 흐름도(CFD) 데이터 반영
```

**동작 원리**

1. **완료 및 가용 슬롯 확보**: 하류 단계의 카드가 다음 공정으로 이동하여 작업 슬롯 여유 생성
2. **WIP 정책 검증**: 대상 컬럼의 현재 작업 수가 명시된 WIP Limit보다 작음을 확인
3. **작업 당김(Pull)**: 밀어넣기(Push)를 배제하고 상류 버퍼에서 최상위 우선순위 카드를 인입
4. **흐름 최적화**: 체류 시간이 긴 카드를 식별(Work Item Aging 관리)하여 병목 집중 해소
5. **메트릭 산출**: 착수 시점부터 배포 완료까지의 리드타임과 일별 처리량을 통계화

#### 한줄 요약
- 하류 단계의 유휴 용량 발생 시 상류 작업을 인입(Pull)하고 체류 시간을 모니터링하여 흐름을 유지한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **스크럼반(Scrumban)**: 스크럼의 역할 정의 및 이벤트(일일 회고 등)와 칸반의 WIP 제한 및 흐름 시각화를 결합한 하이브리드 애자일 프레임워크.

</details>

| 비교 항목 | 칸반 (Kanban) | 스크럼 (Scrum) | 스크럼반 (Scrumban) |
|:---|:---|:---|:---|
| **적용 기준** | 상시 운영·유지보수, 헬프데스크, 장애 대응 | 기능 개발 중심 신규 프로젝트, 제품 릴리즈 | 개발과 긴급 운영 업무가 혼재된 복합 팀 |
| **실행 단위** | 지속적 흐름 (Continuous Flow) | 1~4주 고정 타임박스 (Sprint) | 유연한 이터레이션 및 이벤트 결합 |
| **제약 메커니즘** | 공정별 **WIP Limit** 통제 | 스프린트 기간 및 스프린트 백로그 동결 | 버퍼 크기 기반 동적 계획 수립 |
| **핵심 성과 지표** | 리드타임, 사이클타임, 처리량 | 스프린트 속도(Velocity), 번다운 차트 | 리드타임 및 릴리즈 안정성 |

#### 한줄 요약
- 예측 가능한 계획 중심에는 스크럼을, 변동성이 크고 지속적 대응이 필요한 환경에는 칸반을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **작업 노화(Work Item Aging)**: 특정 작업 카드가 예상 리드타임보다 오랜 기간 특정 공정에 정체되어 병목을 유발하는 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 상위 부서의 과도한 작업 밀어넣기(Push)로 인한 공정 마비 | 보드별 **WIP Limit** 엄격 준수 및 용량 초과 시 신규 착수 중단 | 컨텍스트 스위칭 감소 및 작업 완료율 향상 |
| 특정 컬럼 내 작업 정체 및 **작업 노화(Aging)** 누적 | 일일 스탠드업 미팅 시 노화 카드 중심 검토 및 스워밍(Swarming) 협업 | 병목 조기 해소 및 전체 리드타임 지연 예방 |
| **긴급 트랙(Expedite Lane)** 남용으로 인한 일반 공정 기아 현상 | 긴급 트랙 슬롯을 시스템 전체에서 최대 1개로 제한 | 우선순위 왜곡 방지 및 표준 작업 흐름 안정성 사수 |

#### 한줄 요약
- WIP 제한 준수와 노화 카드 협업 처리(Swarming), 긴급 트랙 엄격 통제로 작업 흐름을 유지한다.

## Ⅶ. 결론

- 긴급 장애 조치 및 지속적 운영 지원이 핵심인 SM/ITSM 조직은 **칸반(Kanban)** 의 연속 흐름 모델을 채택하고, 정기적 마일스톤 배포가 중요한 신규 개발 프로젝트는 **스크럼(Scrum)** 또는 **스크럼반(Scrumban)** 을 적용하여 가치 전달 속도와 예측 가능성을 극대화

#### 한줄 요약
- 워크로드의 변동성과 반복 배포 요구사항에 맞추어 칸반과 스크럼의 흐름 제어 기법을 최적화한다.
