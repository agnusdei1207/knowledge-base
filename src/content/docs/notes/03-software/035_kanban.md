## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **칸반(Kanban)**: 작업 흐름을 시각화하고 진행 중 작업 한도와 당김으로 관리하는 방법이다.
- **진행 중 작업(Work in Progress, WIP)**: 착수했지만 아직 완료하지 않은 작업이다.
- **당김 시스템(Pull System)**: 다음 단계에 처리 여유가 생길 때만 새 작업을 가져오는 방식이다.

</details>

- 정의/개념: **흐름 시각화•WIP 한도•당김**으로 작업을 제어하는 방식이다.
- 배경/필요성: 동시 작업의 과다 착수로 **대기•병목•납기 변동**이 증가한다.

#### 한줄 요약

- WIP 한도와 당김으로 **과다 착수•대기 누적**을 방지한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **리틀의 법칙(Little's Law)**: 안정 상태에서 평균 진행 중 작업 수가 처리율과 평균 리드타임의 곱이라는 관계다.
- **연속 흐름**: 고정 반복 없이 실제 수요와 단계 수용량에 따라 작업을 계속 이동시키는 방식이다.
- **점진적 진화**: 기존 역할과 절차를 유지하며 흐름 데이터를 바탕으로 조금씩 개선하는 접근이다.
- **완료 우선(Finish First)**: 새 작업 착수보다 진행 중이거나 막힌 작업을 끝내는 데 먼저 역량을 쓰는 원칙이다.
- **병목(Bottleneck)**: 처리 능력이 가장 낮아 전체 흐름의 처리량과 대기를 제한하는 단계다.

</details>

![리틀의 법칙에 따른 WIP와 평균 리드타임 관계](/study/diagrams/little-law-wip-lead-time.svg)

> 처리율을 하루 2건으로 고정한 파란 선은 WIP가 10건이면 평균 리드타임이 5일이 되는 리틀의 법칙 예시이며, 안정적인 유입•처리율을 가정한다.

- **완료 우선**으로 대기•병목 중심을 개선한다.
- **연속 흐름**으로 실제 서비스 수요를 처리한다.
- **점진적 진화**로 기존 역할•절차를 개선한다.

#### 한줄 요약

- 흐름 시각화•완료 우선•**점진적 진화** 결합이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **작업 카드(Work Item)**: 업무의 가치•우선순위•차단 상태와 현재 위치를 보드에 표현하는 단위다.
- **워크플로(Workflow)**: 요청부터 완료까지 작업이 거치는 단계의 흐름이다.
- **체류시간(Flow Time in State)**: 작업 카드가 한 워크플로 단계에 머문 시간이다.
- **흐름 정책(Flow Policy)**: 카드의 진입과 이동 및 완료를 정하는 규칙이다.
- **흐름 지표(Flow Metric)**: 리드타임과 처리량 및 체류시간을 측정하는 지표다.

</details>

```text
                   [작업 카드]
                        |
[흐름 정책] ----- [워크플로 열] ----- [흐름 지표]
```

선의 의미: 선은 워크플로 열을 중심으로 작업 카드의 현재 위치, 흐름 정책과 흐름 지표가 결합되는 정적 보드 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 작업 카드 | **가치•우선순위•차단 상태** 표현 |
| 워크플로 열 | 실제 **단계•현재 위치** 시각화 |
| 흐름 정책 | **WIP•당김•완료 규칙** 정의 |
| 흐름 지표 | **리드타임•처리량•체류시간** 측정 |

#### 한줄 요약

- 카드•워크플로•정책•**흐름 지표 구조**가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **수용량•WIP 확인**: 다음 단계의 현재 작업 수와 WIP 한도를 비교하는 단계다.
- **당김 허용 판정**: 다음 단계에 여유가 있을 때만 새 작업 이동을 승인하는 단계다.
- **우선순위 카드 선택**: 상위 단계에서 정책상 가장 먼저 처리할 작업을 고르는 단계다.
- **카드 이동•작업 수행**: 선택한 작업을 다음 열로 옮겨 완료 조건까지 처리하는 단계다.
- **완료•흐름 지표 갱신**: 작업을 완료 열로 옮기고 리드타임•처리량•체류시간을 기록하는 단계다.

</details>

```text
┌──────────────────────────────┐
│ 상위 단계•백로그           │◀──────────────┐
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 1. 수용량•WIP 확인         │               │
└───────┬──────────────────────┘               │
        ├─ 한도 도달 ─▶ [기존 작업 완료 우선]─┘
        │ 여유
        ▼
┌──────────────────────────────┐
│ 2. 당김 허용 판정          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 우선순위 카드 선택      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 카드 이동•작업 수행     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 완료•흐름 지표 갱신     │
└──────────────┬───────────────┘
               ▼
        [다음 작업 당김 판단]
```

**동작 원리**

- **1. 수용량•WIP 확인**: 현재 작업 수와 단계 한도를 비교한다.
- **2. 당김 허용 판정**: 한도 아래일 때 새 작업 승인한다.
- **3. 우선순위 카드 선택**: 상위 목록에서 다음 작업을 결정한다.
- **4. 카드 이동•작업 수행**: 다음 열에서 완료 조건을 처리한다.
- **5. 완료•흐름 지표 갱신**: 완료 반영과 지표를 기록한다.

#### 한줄 요약

- WIP 여유에 따른 **당김•완료 우선** 흐름이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **시간 상자(Timebox)**: 시작과 종료 시간을 고정한 작업 기간이다.
- **스크럼(Scrum)**: 고정 길이 스프린트 목표와 제품 증분으로 작업을 관리하는 애자일 프레임워크다.

</details>

| 작업 흐름 운영 방식 | 칸반 | 스크럼 |
|:---|:---|:---|
| 적용 기준 | 불규칙 유입•**서비스 흐름** | 제품 증분•**시간 상자 목표** |
| 핵심 특징 | **WIP 제한•당김**•연속 흐름 | **스프린트•목표**•제품 증분 |
| 한계 | 우선순위 변동•**병목 고착** | 스프린트 과부하•**행사 형식화** |

> 요약: 칸반은 WIP•연속 흐름, 스크럼은 시간 상자 중심이 핵심이다.

#### 한줄 요약

- 불규칙 서비스 흐름은 칸반, 시간 상자는 **스크럼**이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **사이클타임(Cycle Time)**: 작업 착수부터 완료까지 걸린 시간이다.
- **작업 노화(Work Item Aging)**: 완료되지 않은 작업이 접수•착수 후 경과한 시간이다.
- **서비스 수준 기대(Service Level Expectation, SLE)**: 특정 작업 유형이 정한 시간 안에 완료될 것으로 기대하는 확률 기반 목표다.
- **협업 집중(Swarming)**: 새 작업 착수보다 막히거나 오래된 작업의 완료에 여러 사람이 함께 집중하는 방식이다.
- **긴급 통로(Expedite Lane)**: 즉시 대응할 작업을 일반 흐름과 분리하되 진입 조건과 동시 수를 제한하는 경로다.
- **부분 최적화(Local Optimization)**: 한 단계의 생산성은 높아져도 전체 요청의 리드타임이나 처리량은 악화되는 상태다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근거 없는 **WIP 한도** 고정으로 흐름 왜곡 | **처리량•사이클타임**을 보며 한도 실험 | 실제 수용량에 맞는 **한도** |
| 긴급 통로 남용으로 일반 작업 장기 대기 | 긴급 조건•동시 수•승인자 명시 | 일반 작업의 **우선순위 침해** 통제 |
| 차단•노화 카드에도 새 작업만 착수 | **작업 노화•SLE** 경고와 협업 집중 적용 | 오래된 작업의 **완료 촉진** |
| 단계별 생산성 개선으로 전체 시간 악화 | 요청부터 완료까지 **리드타임**으로 개선 | **부분 최적화** 방지 |

#### 한줄 요약

- WIP•노화•SLE로 **흐름 정책**을 조정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **불규칙 유입**: 작업 요청의 도착 시점과 양이 일정하지 않은 업무 특성이다.
- **시간 상자 목표**: 고정된 기간 안에 달성할 제품 결과와 작업 범위를 정한 목표다.

</details>

- 유입이 불규칙하면 **칸반**, 시간 상자 목표가 중요하면 **스크럼**을 선택한다.

#### 한줄 요약

- 불규칙 유입은 칸반, 시간 상자 목표는 **스크럼**이 핵심이다.
