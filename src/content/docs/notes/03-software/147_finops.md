## 미리 알고가기

- **핀옵스(FinOps)**: ‘핀옵스’로 읽고 Finance와 DevOps를 결합한 관례 명칭으로 별도 약어 확장을 만들지 않으며 클라우드 비용과 가치를 함께 관리하는 운영 체계이다
- **비용할당**: 태그 등으로 비용을 팀에 귀속한다
- **단위경제**: 업무 단위당 비용과 가치를 연결한다
- **사용량최적**: 불필요 자원을 제거하여 조절한다
- **요율최적**: 약정 할인으로 비용 효율을 높이다
- **순환단계**: 정보를 이해하고 최적화 후 운영한다
- **태그·원가 중심**: 태그는 자원 분류값이고 원가 중심은 비용을 책임지는 조직 단위이다
- **정규화**: 공급자마다 다른 청구 항목을 공통 이름과 단위로 바꾸는 과정이다
- **최적화 백로그**: 비용·효과·위험에 따라 실행 순서를 정한 개선 작업 목록이다
- **크기 조정·약정 할인**: 크기 조정은 자원 용량을 맞추고 약정은 사용 약속으로 요율을 낮춤
- **적용률**: 구매한 할인 약정 중 실제 사용량에 적용된 비율이다

## Ⅰ. 개요

- **정의/개념**: 비용 가시성 확보와 자원 최적화 방법론이다
- **배경/필요성**: 비용 소유·가치가 불명확해 단위 경제 측정 필요

### 쉽게 이해하기 (학습용)
- 청구서를 줄이는 기법보다 비용과 업무 가치를 함께 결정하는 방식이다

## Ⅱ. 특징

- 태그와 조직 정보를 결합하여 비용을 귀속한다.
- 예산과 사용 데이터를 연결해 원인을 추적한다.
- 사용량과 요율을 분리해 약정 효과를 구분한다.
- 비용 총액보다 단위 지표로 가치를 판단한다.

### 쉽게 이해하기 (학습용)
- 얼마를 썼는지보다 누가 왜 썼는지를 가치와 연결한다

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    A[비용·사용량 수집] --> B[할당 메타데이터]
    B --> C[보고·예측·단위 경제성]
    C --> D[최적화 백로그]
    D --> E[거버넌스·자동화]
```

| 설계 요소 | 설명 |
|:---|:---|
| 비용·사용량 수집 | 공급자별 청구와 자원 사용 데이터를 정규화함 |
| 할당 메타데이터 | 계정과 태그를 제품 및 원가 중심에 연결함 |
| 보고·예측·단위 경제성 | 현재 비용을 비교하고 업무 단위 비용으로 환산함 |
| 최적화 백로그 | 사용량과 요율 및 대안의 가치를 기록함 |
| 거버넌스·자동화 | 정책·승인·조치와 결과 측정을 반복함 |

> 요약: 사용량을 업무 단위에 귀속하고 최적화 결과를 반영한다

### 쉽게 이해하기 (학습용)
- 청구 데이터를 팀과 서비스에 연결하고 결과를 추적한다

## Ⅳ. 원리 및 절차 흐름도

| 절차 | 설명 |
|:---|:---|
| **수집정규** | 공급자 청구 항목을 공통 형식으로 변환함 |
| **비용할당** | 태그와 계정 정보로 부서별 비용을 배분함 |
| **이상확인** | 예산 차이와 급증 항목의 발생 원인을 찾음 |
| **대안평가** | 자원 조정과 요율 변경의 기대 효과를 비교함 |
| **효과측정** | 최적화를 적용하고 절감 비용과 지표를 확인함 |

> 요약: 할당된 비용에서 대상을 찾고 효과를 다음 주기에 반영한다

### 쉽게 이해하기 (학습용)
- 예상보다 실제 비용과 영향이 어떻게 바뀌었는지 확인한다

## Ⅴ. 종류 및 비교

| 비교축 | Inform | Optimize | Operate |
|:---|:---|:---|:---|
| 핵심 특징 | 누가 얼마를 쓰는지 확인함 | 어떤 변경이 비용을 줄이는지 판단함 | 선택한 변경이 성과를 냈는지 검증함 |
| 적용 기준 | 사용량과 비용 현황을 투명하게 파악할 때 | 낭비 자원을 식별하고 할인 약정을 적용할 때 | 최적화 정책을 자동화하고 비즈니스와 연계할 때 |
| 주요 위험 | 태그 누락·비용 배분 오류 | 과도한 절감·성능 저하 | 정책 미집행·절감 회귀 |

> 요약: 비용 근거로 대안을 정하고 실현 효과를 반영한다

### 쉽게 이해하기 (학습용)
- 비용을 시각화하고 개선안을 선택해 효과를 확인하는 순환이다

## Ⅵ. 실무 사례

1. 컨테이너 비용을 할당하고 요청당 비용을 확인한다
2. 상시 서버는 약정 범위를 맞추고 적용률을 확인한다

### 쉽게 이해하기 (학습용)
- 컨테이너는 팀별 요청당 비용으로 낭비를 찾음
- 상시 서버는 약정 적용률과 남은 용량을 확인한다

## Ⅶ. 결론

- 단위 비용이 줄고 성능을 지킨 최적화만 유지한다

### 쉽게 이해하기 (학습용)
- 싸졌어도 서비스가 느려지면 좋은 절감이 아님
