## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **FinOps (Financial Operations)**: 엔지니어링, 재무, 비즈니스 조직이 협력하여 클라우드 비용을 투명하게 가시화(Inform), 최적화(Optimize), 운영(Operate)하는 재무 거버넌스 프레임워크.
- **클라우드 비용 폭증 및 귀속 불투명(Cloud Cost Overrun & Attribution Gap)**: 종량제 인프라의 무분별한 프로비저닝으로 인해 예산이 초과되고 부서별 원가 측정이 불가능해지는 위험.

</details>

- 정의/개념: 엔지니어링, 재무, 비즈니스 조직이 협력하여 **클라우드 비용을 가시화(Inform), 최적화(Optimize), 운영(Operate)하는 재무 거버넌스** 체계
- 배경/필요성: 종량제 클라우드 자원의 무분별한 프로비저닝으로 인한 **클라우드 비용 폭증, 팀별 비용 귀속 불투명 및 단위 경제성 측정 불가 위험** 직면

#### 한줄 요약

- 정보 가시화, 리소스 최적화, 지속적 운영의 3단계 순환을 통해 비즈니스 가치 중심의 클라우드 재무 최적화를 달성

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **단위 경제성(Unit Economics)**: 단순한 총비용 절감이 아닌 '주문 1건당 인프라 비용' 또는 '활성 사용자 1명당 클라우드 원가'를 측정하는 핵심 지표.
- **3대 라이프사이클(Inform, Optimize, Operate)**: 비용 귀속 및 가시화(Inform) $\to$ 자원 사이징 및 약정 할인(Optimize) $\to$ 거버넌스 자동화(Operate).

</details>

- 모든 클라우드 자원에 태그(Tagging)를 부여하여 **팀별·제품별 100% 비용 귀속(Cost Attribution)**
- 라이트사이징(Right-sizing)과 약정 할인(Savings Plans)을 통한 **지속적 리소스 및 요율 최적화**
- 비즈니스 매출과 연계하여 클라우드 ROI를 측정하는 **단위 경제성(Unit Economics) 기반 의사결정**

#### 한줄 요약

- 가시화, 최적화, 자동화 거버넌스를 통해 클라우드 투자 대비 비즈니스 가치를 극대화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **FinOps 3단계 라이프사이클**: Inform(가시화/예측), Optimize(사용량/요율 최적화), Operate(정책/자동화 거버넌스).

</details>

```text
[ FinOps 3단계 지속 순환 프레임워크 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      FinOps 지속 순환 라이프사이클                     │
 ├────────────────────────────────────────────────────────────────────────┤
 │   ┌───────────────────────┐             ┌────────────────────────┐     │
 │   │ 1. Inform (정보 가시화)│ ──────────► │ 2. Optimize (자원 최적화)│   │
 │   │  - 태깅 기반 비용 귀속 │             │  - Right-Sizing (다운) │     │
 │   │  - Unit Economics 측정│             │  - RI / Savings Plans  │     │
 │   │  - 예산 예측 및 알림   │             │  - Spot / 아키텍처 개선 │     │
 │   └───────────────────────┘             └───────────┬────────────┘     │
 │               ▲                                     │                  │
 │               │                                     ▼                  │
 │               │                         ┌────────────────────────┐     │
 │               └─────────────────────────│ 3. Operate (자동화 운영) │   │
 │                                         │  - Policy-as-Code 통제 │     │
 │                                         │  - 주말 자동 셧다운    │     │
 │                                         │  - FinOps 문화 정착     │     │
 │                                         └────────────────────────┘     │
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: Inform(가시화)에서 Optimize(최적화)로, Optimize에서 Operate(운영)로 지속 순환하는 FinOps 루프.

| 구성요소 | 책임 |
|:---|:---|
| Inform 계층 (가시화) | 자원 태깅, 예산 예측, 팀별 비용 귀속 및 **Unit Economics(건당 원가) 산출** |
| Optimize 계층 (최적화) | 미사용 자원 정리, Right-Sizing, **Savings Plans(약정 할인) 및 Spot 인스턴스 적용** |
| Operate 계층 (운영) | 비업무 시간 자동 정지, FinOps KPI 수립, **비용 이상 탐지(Anomaly) 자동 알림** |
| FinOps 전담 조직 | 개발, 재무, 사업 간 협업을 조율하고 **전사 클라우드 비용 효율성 가이드라인 배포** |

#### 한줄 요약

- Inform(가시화), Optimize(최적화), Operate(자동화 운영)가 결합하여 비용 낭비를 제거

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **FinOps 실행 5단계 파이프라인**: 비용 귀속 $\to$ 단위 경제성 측정 $\to$ 최적화 후보 도출 $\to$ 자원/요율 개선 $\to$ 효과 검증.

</details>

```text

 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
```

### 동작 원리

1. 비용 귀속: AWS Cost Allocation Tagging(`Team`, `Service`, `Env`)을 통해 모든 인프라 비용을 소유자별로 100% 매핑.
2. 단위 경제성 측정: 주문 1건당 또는 API 1만 건당 소요된 클라우드 원가를 계산하여 비즈니스 효율을 분석.
3. 후보 평가: AWS Compute Optimizer를 활용해 CPU 사용률 10% 미만의 과다 프로비저닝 인스턴스를 식별.
4. 최적화 실행: 개발 서버는 주말 자동 중지하고, 베이스라인 트래픽에 대해 Compute Savings Plans(최대 66% 할인)를 체결.
5. 품질 검증: 비용 절감 후에도 시스템 레이턴시와 에러율이 목표 SLO를 충족하는지 검증하고 루프를 반복.

#### 한줄 요약

- 비용 귀속 $\to$ 단위 원가 측정 $\to$ 후보 도출 $\to$ 최적화 실행 $\to$ 품질 검증의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전통적 IT 예산 vs FinOps**: 연 1회 사후 정산의 고정 CapEx 예산 관리와 실시간 사용량 기반 능동적 OpEx FinOps.

</details>

| 구분 | 전통적 IT 예산 관리 (CapEx) | 현대적 FinOps 프레임워크 (OpEx) |
|:---|:---|:---|
| **적용 기준** | 연간 고정 인프라 구매 및 하드웨어 감가상각 환경 | 실시간 종량제 클라우드 및 멀티 클라우드 환경 |
| **핵심 특징** | **사후 정산 중심, 재무팀 독점 통제, 자원 구매 억제** | **실시간 가시화, 개발·재무·사업 협업, Unit Economics** |
| **한계** | 트래픽 변동에 유연하게 대응 불가 및 자원 낭비 | 전사 문화 정착 및 정밀 태깅 관리 오버헤드 |

#### 한줄 요약

- 연간 사후 통제는 전통적 예산 관리, 실시간 단위 원가 기반 협업 최적화는 FinOps를 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **미할당 자원(Untagged Resources)**: 태그 없이 생성되어 비용 주체를 알 수 없는 리소스로, FinOps 가시성을 파괴하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 태그 미부착 자원(Untagged) 누적으로 비용 귀속 마비 | **IaC (Terraform) CI/CD에서 태그 미입력 시 프로비저닝 차단** | 자원 태깅 준수율 99% 이상 달성 |
| 주말 및 야간에도 개발/테스트용 EC2가 24/7 가동되어 낭비 | **EventBridge 및 Lambda 기반 비업무 시간 인스턴스 자동 정지** | 개발 인프라 비용 60% 즉시 절감 |
| 서비스 조기 종료로 3년 고정 RI(예약 인스턴스) 약정 손실 | **인스턴스 패밀리/리전 변경이 자유로운 Flexible Savings Plans 구매** | 약정 위약금 리스크 없이 최대 할인율 확보 |

#### 한줄 요약

- 태깅 강제, 비업무 시간 자동 정지, 유연한 Savings Plans 도입을 통해 실질적 비용 절감을 달성

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **클라우드 재무 문화(Cloud Financial Culture)**: 개발자가 코드를 작성할 때부터 비용 효율성을 설계 요소로 내재화하는 엔지니어링 문화.

</details>

- **FinOps** 기반 클라우드 네이티브 환경에서 기업의 수익성과 엔지니어링 민첩성을 동시에 견인하는 핵심 거버넌스 체계이며, Inform-Optimize-Operate 3대 라이프사이클을 전사 문화로 내재화하여 클라우드 투자의 가치를 극대화해야 함

#### 한줄 요약

- 가시화, 리소스 최적화, 자동화 거버넌스를 통해 클라우드 비용을 절감하고 비즈니스 ROI를 완성
