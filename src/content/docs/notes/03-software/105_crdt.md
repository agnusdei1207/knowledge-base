## 미리 알고가기

- **충돌 없는 복제 데이터 유형(Conflict-free Replicated Data Type, CRDT)**: 여러 복제본의 동시 변경을 결정적 규칙으로 자동 수렴시키는 자료형임
- **상태 기반 CRDT(State-based CRDT)**: 전체 상태나 차이를 교환·결합·멱등 병합해 수렴하는 유형임
- **연산 기반 CRDT(Operation-based CRDT)**: 변경 연산을 신뢰성 있게 전달하고 교환 가능한 규칙으로 적용하는 유형임
- **교환 법칙(Commutativity)**: 연산이나 병합의 순서를 바꿔도 결과가 같은 성질임
- **결합 법칙(Associativity)**: 여러 값을 묶어 병합하는 순서를 바꿔도 결과가 같은 성질임
- **멱등성(Idempotence)**: 같은 상태나 연산을 여러 번 적용해도 한 번 적용한 결과와 같은 성질임
- **인과 메타데이터(Causal Metadata)**: 버전 벡터·논리 시계로 변경의 선후 관계와 중복 여부를 나타내는 정보임
- **상태 델타(State Delta)**: 전체 상태 중 다른 복제본에 전달할 변경 차이만 표현한 값임
- **안티엔트로피(Anti-entropy)**: 복제본끼리 상태 차이를 주기적으로 교환해 누락 변경을 보완하는 동기화 방식임
- **업무 불변식(Business Invariant)**: 재고가 음수가 아니어야 하는 것처럼 모든 처리 뒤에도 지켜야 하는 업무 규칙임

## Ⅰ. 개요

- **정의/개념**: 동시 변경을 자료형 규칙으로 자동 수렴시킴
- **배경/필요성**: 단절 중 동시 쓰기 충돌로 수렴 병합 필요

### 쉽게 이해하기 (학습용)
- 같은 문서를 고쳐도 정해진 병합 규칙으로 같은 결과를 만드는 자료형임

## Ⅱ. 특징

- 중앙 잠금 없이 갱신해 단절 중 쓰기 가용성을 유지한다.
- 수렴 조건을 지키면 전파 순서와 무관하게 합쳐진다.
- 자료형별 동시 변경 의미를 병합 규칙에 명시한다.
- 메타데이터가 누적되고 업무 불변식은 별도 조정한다.

### 쉽게 이해하기 (학습용)
- 동시 변경을 받아들이지만 업무 규칙까지 자동으로 보장하지는 않음

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 복제본 상태 | 각 노드가 로컬 처리에 사용하는 값을 유지함 |
| 상태 델타·변경 연산 | 다른 복제본에 전파할 상태 차이 또는 명령을 표현함 |
| 인과 메타데이터 | 버전 벡터와 논리 시계로 선후 관계와 중복을 판정함 |
| 병합·적용 함수 | 연산을 적용해 자료형별 수렴 규칙을 실행함 |
| 전파 계층 | 안티엔트로피나 메시지 브로커로 변경을 최종 전달함 |

```text
  로컬갱신
      ↓
  델타전파
      ↓
  함수병합
      ↓
  상태수렴
```

> 요약: 델타·인과 정보·병합 함수로 상태 수렴

### 쉽게 이해하기 (학습용)
- 사본의 값과 변경표 및 순서표와 병합 함수를 함께 가진 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
  변경수락
      ↓
  단위생성
      ↓
  내용전파
      ↓
  결과병합
```

| 절차 | 설명 |
|:---|:---|
| **로컬 변경 수락** | 복제본이 현재 상태에 사용자 변경을 반영함 |
| **전파 단위 생성** | 상태 기반은 델타를 만들고 연산 기반은 식별자를 생성함 |
| **복제본 전파** | 메시지 계층이 변경 내용을 다른 복제본에 전달함 |
| **병합·적용** | 상태를 멱등 병합하고 연산 기반은 중복을 제거함 |
| **수렴·불변식 확인** | 상태 일치와 별도 조정이 필요한 업무 불변식을 확인함 |

> 요약: 상태는 멱등 병합, 연산은 중복 제거

### 쉽게 이해하기 (학습용)
- 로컬 변경을 다른 사본에 보내 중복을 거르고 같은 상태로 합침

## Ⅴ. 종류 및 비교

| 판단 기준 | 상태 기반 CRDT | 연산 기반 CRDT |
|:---|:---|:---|
| 핵심 특징 | 상태 또는 델타를 전파함 | 생성한 연산을 전파함 |
| 수렴 조건 | 교환과 결합 및 멱등 성질을 충족함 | 교환 가능하고 중복 적용하지 않아야 함 |
| 적용 기준 | 크기가 제한되고 비정기 동기화에 적용함 | 변경이 잦고 계층 통제가 가능할 때 적용함 |
| 주요 위험 | 상태 크기·전송량 증가 | 중복·순서 전달 조건 위반 |

> 요약: 상태는 멱등 병합, 연산은 신뢰 전달

### 쉽게 이해하기 (학습용)
- 상태를 합치거나 명령만 전달하는 방식이며 수렴 규칙이 핵심임

## Ⅵ. 실무 사례

1. 공동 편집은 메타데이터를 압축하고 재동기화 시간을 확인함
2. 오프라인 현장 앱은 델타를 전송하고 수렴 시간을 확인함

### 쉽게 이해하기 (학습용)
- 공동 편집은 동시 삽입·삭제의 위치를 CRDT 규칙으로 수렴시키고 메타데이터 크기와 재동기화 시간을 관리함
- 오프라인 현장 앱은 로컬 변경 델타를 연결 복구 뒤 전파하되 재고 음수 같은 업무 불변식은 별도 조정으로 지켜야 함

## Ⅶ. 결론

- 변경 빈도·전달 조건·불변식에 맞는 CRDT 선택

### 쉽게 이해하기 (학습용)
- CRDT는 복제본의 기술적 수렴을 보장하지만 메타데이터 비용과 업무적으로 허용할 수 없는 결과까지 자동 해결하지는 않음
