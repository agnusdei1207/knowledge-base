## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모놀리식 커널(Monolithic Kernel)**: OS의 모든 짐덩어리(파일, 네트워크, 드라이버)를 한 바구니(커널)에 다 때려 넣고 한통속으로 돌리는 깡성능 몰빵 구조이다.
- **마이크로커널(Microkernel)**: 커널 안에는 핵심만 딱 남기고, 나머지 잡다한 기능들은 사용자 공간(유저 서버)으로 매정하게 쫓아내서 뼈대만 앙상하게 남긴 모듈형 구조이다.
- **하이브리드 커널(Hybrid Kernel)**: 모놀리식의 미친 속도와 마이크로커널의 깔끔한 모듈 분리를 적당히 섞은 윈도우/맥오에스의 절충형 구조이다.

</details>

- 정의: OS 커널을 거대하게 하나로 퉁칠 건지(모놀리식), 아니면 뼈대만 남기고 다 찢어버릴 건지(마이크로)를 결정하는 **커널 2대 설계 철학**
- 배경: 모놀리식은 드라이버 하나만 뻑나도 **시스템 전체가 죽어버리니까(장애 전파)**, 이걸 쪼개서 막아보려고 마이크로커널이 등장함

#### 한줄 요약

- OS 기능을 한 덩어리에 다 때려 박으면 모놀리식, 뼈대만 남기고 유저 공간으로 쫓아내면 마이크로커널이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IPC 오버헤드(IPC Overhead)**: 마이크로커널에서 유저 서버끼리 말 섞을 때마다 커널이 강제로 우체부 역할을 하느라 딜레이가 미친 듯이 치솟는 뼈아픈 부작용이다.
- **결함 격리(Fault Isolation)**: 드라이버나 파일 시스템이 유저 공간에서 돌기 때문에, 그놈들이 뻗어도 OS 전체는 멀쩡히 살아서 해당 놈만 재시작하면 땡인 방탄 속성이다.

</details>

- 커널 주소 공간 하나에서 다이렉트로 때려 박는 **모놀리식 커널**의 압도적 스피드.
- 서비스를 유저 공간으로 쫓아내서 버그가 나도 시스템을 살리는 **마이크로커널**의 방어력.
- 결국 **IPC 오버헤드**를 감당하고 생존력을 챙길지, 위험을 안고 속도에 몰빵할지의 치킨 게임임.

#### 한줄 요약

- 모놀리식은 다이렉트 호출의 깡성능, 마이크로커널은 결함 격리의 철통 방어가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **유저 공간 서버(User-Space Server)**: 마이크로커널이 커널에서 쫓아낸 네트워크, 파일 시스템 놈들이 일반 프로그램(유저 모드)처럼 격리되어 도는 서비스 덩어리들이다.

</details>

```text
[ 2대 커널 아키텍처 십자포화 구조 ]

[ 마이크로커널 (모듈 찢음) ]    [ 모놀리식 커널 (한통속) ]
┌── 유저 공간 (안전) ──┐        ┌── 유저 공간 ──┐
│ [파일 서버] [드라이버]│        │   [응용 앱]   │
│         │          │        └──────┬──────┘
├─── IPC 통신 횡단 ────┤               ▼ 시스템 콜
│         ▼          │        ┌── 커널 공간 ──┐
│   [ 마이크로커널 ]   │        │[모놀리식 커널]│
│   (핵심만 뼈대만)    │        │(파일/네트워크)│
└────────────────────┘        └───────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| 마이크로커널 | 프로세스, 메모리 관리, IPC 통신 중계 등 OS가 숨 쉬는 데 필요한 진짜배기 최소 기능 |
| **유저 공간 서버** | 커널에서 쫓겨난 파일 시스템, 장치 드라이버들이 일반 앱처럼 유저 모드에서 구동되는 독립 용병들 |
| **모놀리식 커널** | 파일 시스템부터 자잘한 드라이버까지 싹 다 하나의 커널 메모리에 때려 박은 거대 엔진 |

#### 한줄 요약

- 마이크로커널은 IPC 통신으로 유저 서버를 부리고, 모놀리식 커널은 지가 다 끌어안고 산다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **컨텍스트 스위치 페널티(Context Switch Penalty)**: 마이크로커널에서 I/O 하나 하려고 유저 ➔ 커널 ➔ 서버 ➔ 커널 ➔ 유저로 끝없이 문맥 전환을 널뛰기하며 시간을 다 까먹는 끔찍한 병목이다.

</details>

```text
[ 커널 실행 경로 십자포화 흐름 ]

[ 마이크로커널 (IPC 똥꼬쇼) ]
┌──────────────────────────────┐
│ 1. 시스템 호출 (앱 ➔ 커널)    │
└──────────────┬───────────────┘
               ▼ (커널 중계)
┌──────────────────────────────┐
│ 2. IPC 메시지로 유저 서버 찌름│
└──────────────┬───────────────┘
               ▼ (다시 커널 거침)
┌──────────────────────────────┐
│ 3. 결과 반환 (서버 ➔ 커널 ➔ 앱)│
└──────────────────────────────┘

[ 모놀리식 커널 (다이렉트 꽂음) ]
┌──────────────────────────────┐
│ 1. 시스템 호출 (앱 ➔ 커널)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 커널 내부에서 다이렉트 처리│
│ (내 집 안방이라 바로 처리 완료)│
└──────────────────────────────┘
```

### 동작 원리

1. 마이크로커널 IPC 널뛰기: 앱이 커널 부르면 ➔ 커널이 다시 유저 서버 부르고 ➔ 유저 서버가 커널한테 답 주고 ➔ 커널이 앱에 답 주는 무한 핑퐁.
2. 모놀리식 다이렉트: 앱이 커널 부르면 ➔ 커널 메모리 안에 다 있으니까 함수 부르듯 다이렉트 처리하고 바로 쏴줌.

#### 한줄 요약

- 마이크로커널은 커널과 유저 서버 사이를 무한 핑퐁하고, 모놀리식은 한 큐에 끝낸다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **seL4**: 수학적 증명(정형 명세)으로 "우리 커널 코드는 버그가 절대 0%임"을 전 세계 최초로 기계 검증해버린 무결성 끝판왕 마이크로커널이다.

</details>

| 비교 항목 | **모놀리식 커널** (Linux) | **마이크로커널** (QNX, seL4) |
|:---|:---|:---|
| 신뢰 컴퓨팅(TCB) | 덩치가 산만해서 코드 한 줄만 꼬여도 다 같이 죽음 | 뼈대만 남겨서 **버그가 숨을 공간(TCB) 자체가 좁음** |
| 핫 리로딩/장애복구 | 모듈(LKM) 뺐다 낄 순 있지만, 뻑나면 커널 패닉 뜸 | 유저 서버 하나 뻗어도 걍 그 프로세스만 죽이고 **다시 켜면(Restart) 땡** |
| 수학적 검증 | 코드가 수천만 줄이라 정형 검증(수학적 증명) 절대 불가 | 코드가 몇만 줄 안 돼서 수학적으로 완벽하다고 **증명(seL4)** 가능함 |
| 최고존엄 무대 | 범용 서버, PC, 안드로이드 스마트폰 (깡성능 원탑) | 자동차 ECU, 전투기, 의료기기 (안 죽는 방탄 안정성 원탑) |

#### 한줄 요약

- 모놀리식은 빠른 대신 한 번 꼬이면 다 죽고, 마이크로커널은 느린 대신 하나 죽어도 금방 다시 살려낸다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **제로 카피 IPC(Zero-Copy IPC)**: 마이크로커널이 메시지 전달(IPC)할 때 메모리를 이리저리 복사하느라 느려지는 걸 막으려고, 메모리 버퍼를 공유해 버려서 복사 오버헤드를 0으로 만들어버리는 꼼수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 마이크로커널은 IPC 통신하느라 컨텍스트 스위칭 폭탄 맞고 성능이 나락감 | 유저-커널 간 **공유 메모리(Zero-Copy)**로 데이터 걍 쉐어링해 버림 | 메시지 복사하는 헛짓거리를 없애서 IPC 오버헤드 박살 냄 |
| 모놀리식 리눅스 쓰는데 싸구려 그래픽 드라이버 하나 뻑났다고 커널 패닉 옴 | eBPF 같은 샌드박스로 막거나 검증된 **LKM**만 올려서 컷침 | 똥망 드라이버 하나 때문에 서버 전체가 뻗는 대참사 통제 |
| 자율주행 차 만드는데, 블루투스 고장 났다고 브레이크까지 멈추면 큰일 남 | **QNX, seL4** 기반 RTOS 깔아서 기능을 아예 찢어발김 | 블루투스 서버가 죽어도 브레이크 서버는 멀쩡히 도는 **철벽 방어** |

#### 한줄 요약

- IPC 딜레이는 제로 카피로 부수고, 모놀리식 폭탄은 eBPF로 막으며, 생명이 달린 곳엔 마이크로커널을 써라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **커널 아키텍처 선택 기준(Kernel Architecture Selection Criteria)**: 속도가 깡패인지(범용), 사람 목숨이 달려서 무조건 안정적인지(임베디드)에 따라 모놀리식과 마이크로커널을 가르는 잣대이다.

</details>

- **커널 아키텍처 선택 기준** 원칙에 따라, 깡성능 리눅스 서버는 **모놀리식/하이브리드**, 사람 목숨 달린 전장/의료 장비는 **마이크로커널** 채택 기조 확립함

#### 한줄 요약

- 속도전의 리눅스 서버는 모놀리식, 생존전의 자동차와 전투기는 마이크로커널이 정답이다.
