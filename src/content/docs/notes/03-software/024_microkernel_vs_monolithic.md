## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모놀리식 커널(Monolithic Kernel)**: 프로세스 관리, 메모리, 파일 시스템, 네트워크, 디바이스 드라이버 등 모든 OS 서비스를 단일 Ring 0 커널 공간에 포함하는 구조.
- **마이크로커널(Microkernel)**: 스케줄링, 주소 공간, IPC 등 최소 필수 기능만 커널에 남기고 나머지 서비스를 사용자 공간(User-Space) 서버로 분리한 구조.

</details>

- 정의/개념: 모든 OS 서비스를 단일 커널 공간에 통합하는 **모놀리식 커널**과 최소 기능만 남기고 유저 서버로 분리하는 **마이크로커널** 아키텍처
- 배경/필요성: 모놀리식 커널의 드라이버 결함 시 전체 커널 패닉 취약성 및 **마이크로커널의 빈번한 IPC 문맥 전환 오버헤드 한계**

#### 한줄 요약
- 고성능 단일 주소공간(모놀리식)과 결함 격리 및 안전성(마이크로커널)의 설계 패러다임을 비교한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IPC 오버헤드(IPC Overhead)**: 마이크로커널에서 사용자 공간 서버 간 메시지 전달 시 발생하는 잦은 문맥 전환과 메모리 복사 지연.
- **결함 격리(Fault Isolation)**: 특정 드라이버나 파일 시스템에 크래시가 발생해도 해당 유저 프로세스만 재시작하면 되는 마이크로커널의 안전성.

</details>

- **모놀리식 커널**: 커널 내부 직접 함수 호출을 통한 최고 성능, 단일 버그가 전체 시스템 패닉을 유발하는 단점
- **마이크로커널**: 사용자 공간 서버 분리를 통한 완벽한 **결함 격리(Fault Isolation)**, **IPC 오버헤드**로 인한 성능 페널티
- 시스템의 무결성·안전성 요구와 순수 연산 성능 요구 간의 트레이드오프

#### 한줄 요약
- 모놀리식은 고성능이나 장애 전파 위험이 있고, 마이크로커널은 안전하고 신뢰성이 높으나 IPC 지연이 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **유저 공간 서버(User-Space Server)**: 파일 시스템, 네트워크 스택, 장치 드라이버가 커널이 아닌 일반 사용자 권한 프로세스로 격리 구동되는 컴포넌트.

</details>

```text
[커널 아키텍처 모델 체계]
  │
  ├─ [마이크로커널 모델] (결함 격리 및 안전성)
  │     ├─ [유저 공간 Ring 3] (파일·망·드라이버 서버)
  │     └─ [초소형 커널 Ring 0] (스케줄러·메모리·IPC)
  │
  └─ [모놀리식 커널 모델] (직접 호출 및 고성능)
        ├─ [유저 공간 Ring 3] (사용자 응용 프로그램)
        └─ [단일 커널 Ring 0] (VFS·드라이버·네트워크 통합)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 마이크로커널 (Microkernel) | 모놀리식 커널 (Monolithic) |
|:---|:---|:---|
| 커널 내부 (Ring 0) | **스케줄링, 최소 메모리 매핑, IPC** | **VFS, 드라이버, 네트워크, 메모리, IPC 전체** |
| 유저 서버 (Ring 3) | 파일 서버, 네트워크 스택, 드라이버 | 없음 (응용 프로그램만 실행) |
| 통신 메커니즘 | 커널 경유 **IPC 메시지 큐 / 공유 메모리** | 커널 내부 직접 메모리 함수 포인터 호출 |

#### 한줄 요약
- 두 구조는 같은 OS 기능을 커널 안에 둘지 유저 서버로 내보낼지로만 갈리며, 그 경계 위치가 곧 장애 전파 범위와 IPC 비용의 크기를 정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **문맥 전환 페널티(Context Switch Penalty)**: 마이크로커널에서 I/O 요청 시 유저 앱 $\to$ 커널 $\to$ 드라이버 서버 $\to$ 커널 $\to$ 유저 앱으로 이어지는 4회 문맥 전환 오버헤드.

</details>

```text
1. 마이크로커널 파일 읽기 흐름 (IPC 메시지 경유)
    [유저 앱] ──(read 호출)──► [마이크로커널 Ring 0] ──(IPC 전달)──► [파일 서버 Ring 3]
                                                                         │
    [유저 앱] ◄──(read 완료)─── [마이크로커널 Ring 0] ◄──(IPC 전달)─── [디스크 드라이버]
    (다중 모드 전환 및 IPC 문맥 전환 페널티 발생)

2. 모놀리식 커널 파일 읽기 흐름 (커널 내부 직접 호출)
    [유저 앱] ──(read 시스템 콜)──► [모놀리식 커널 Ring 0: VFS -> ext4 -> 디바이스 드라이버]
                                               │ (커널 내부 직접 함수 호출 및 즉각 I/O)
    [유저 앱] ◄────────────────────────────────┘ (단 2회 모드 전환으로 초고속 완료)
```

#### 한줄 요약
- 같은 서비스 요청이라도 마이크로커널은 모드 전환을 여러 번 왕복하고 모놀리식은 함수 호출 한 번으로 끝나므로, 격리 이득은 그 왕복 횟수만큼의 지연으로 지불된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하이브리드 커널(Hybrid Kernel)**: Windows NT, macOS XNU처럼 마이크로커널 구조를 기반으로 하되 성능을 위해 그래픽/파일시스템을 Ring 0에 포함시킨 절충형.

</details>

| 비교 항목 | 모놀리식 커널 (Linux) | 마이크로커널 (QNX, seL4) | 하이브리드 커널 (Windows NT, macOS) |
|:---|:---|:---|:---|
| 실행 성능 | **최고 성능 (직접 호출)** | IPC 오버헤드로 다소 저하 | 고성능 (핵심 서비스 Ring 0 내장) |
| 결함 격리 | 단일 드라이버 버그 시 **커널 패닉** | **서버 크래시 시 단독 재시작 가능** | 드라이버 오류 시 블루스크린(BSOD) |
| 코드 크기 | 수천만 라인 (거대함) | **수만 라인 (수학적 검증 가능)** | 수천만 라인 |
| 주 적용 분야 | 범용 서버, 클라우드, 안드로이드 | **자동차(AUTOSAR), 항공 항법, 의료기기** | 데스크톱, 스마트폰 OS |

#### 한줄 요약
- 성능과 확장성은 모놀리식, 수학적 안전성과 무중단 신뢰성은 마이크로커널, 범용 OS는 하이브리드를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **eBPF(Extended Berkeley Packet Filter)**: 리눅스 모놀리식 커널을 수정하거나 모듈을 빌드하지 않고도 커널 내부에서 안전하게 샌드박스 코드를 실행하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 마이크로커널의 잦은 IPC 문맥 전환으로 인한 성능 저하 | **제로 카피 IPC(Zero-Copy IPC) 및 공유 메모리 링버퍼** 적용 | 메시지 복사 오버헤드 80% 제거 및 처리량 향상 |
| 모놀리식 커널에서 서드파티 모듈 오류로 인한 커널 패닉 | **eBPF 샌드박스 검증기** 및 드라이버 서명 강제 | 커널 주소 공간 오염 원천 차단 |
| 미션 크리티컬 제어 시스템의 무결성 증명 필요 | 정형 검증(Formal Verification) 완료된 **seL4 마이크로커널** 도입 | 버그·취약점 0건의 수학적 보안 증명 확보 |
| 마이크로커널 유저 서버 비정상 종료 시 서비스 중단 | **프로세스 관리자(Process Manager)의 자동 핫 재시작** | 수 밀리초 내 무중단 데몬 자동 복구 |

#### 한줄 요약
- 마이크로커널은 장애 격리를 IPC 왕복 비용으로 사고 모놀리식은 성능을 장애 범위로 사므로, 제로카피 IPC와 eBPF 샌드박스처럼 각 구조가 지불한 대가를 줄이는 보완책을 함께 적용한다.

## Ⅶ. 결론

- 운영체제 커널 설계 및 미션 크리티컬 시스템의 **핵심 2대 아키텍처 패러다임**으로 정립되었으며, 실무에서는 **대규모 클라우드 서버 및 범용 컴퓨팅에는 고성능 모놀리식(Linux + eBPF 안전성 보완), 차량(AUTOSAR Adaptive)·항공·국방 등 생명 안전 필수(Safety-Critical) 임베디드 제어에는 정형 검증된 마이크로커널(QNX, seL4)과 제로 카피 IPC**를 선별 채택

#### 한줄 요약
- 커널 아키텍처는 성능과 결함 격리의 트레이드오프이며, 도메인 안전성 요구에 맞춰 최적의 커널 모델을 선택해야 한다.
