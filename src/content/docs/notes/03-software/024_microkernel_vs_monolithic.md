## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모놀리식 및 마이크로커널(Monolithic & Microkernel)**: VFS·드라이버 등을 단일 커널 공간에 통합(모놀리식)하거나, IPC 기반 사용자 공간 데몬으로 분리(마이크로커널)하는 설계.
- **커널 패닉 및 시스템 다운(Kernel Panic & System Crash)**: 모놀리식 환경에서 불량 드라이버 하나가 커널 주소 공간을 오염시켜 전체 OS가 정지하는 치명적 한계.

</details>

- 정의/개념: 모든 OS 서비스를 단일 주소공간에 통합하는 **모놀리식 구조**와 핵심 기능만 커널에 남기고 서버화하는 **마이크로커널** 아키텍처
- 배경/필요성: 서드파티 드라이버의 커널 공간 오류로 인한 **커널 패닉(Kernel Panic) 및 전체 시스템 다운 위험** 직면

#### 한줄 요약

- OS 기능 전체를 커널에 통합하는 모놀리식의 고성능과 최소 핵심만 커널에 유지하는 마이크로커널의 결함 격리를 비교

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IPC 오버헤드(IPC Overhead)**: 마이크로커널에서 유저 공간 서버 간 통신 시 커널 경유 메시지 전달로 발생하는 컨텍스트 전환 지연.
- **결함 격리(Fault Isolation)**: 사용자 공간 서버의 장애가 커널 공간에 전파되지 않고 해당 서버만 재시작으로 복구 가능한 마이크로커널의 보호 특성.

</details>

- **모놀리식 커널**: 커널 공간 직접 호출로 고성능, 단일 오류가 전체 커널 패닉으로 전파되는 위험
- **마이크로커널**: 사용자 공간 서버 분리로 **결함 격리** 확보, **IPC 오버헤드**로 성능 저하
- 결함 격리 필요성과 성능 요구의 상충 관계가 선택 기준

#### 한줄 요약

- 모놀리식은 커널 직접 호출로 고성능이나 장애 전파 위험, 마이크로커널은 결함 격리가 강하나 IPC 오버헤드 발생

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사용자 공간 서버(User-Space Server)**: 마이크로커널이 사용자 공간에서 실행되도록 분리한 파일 시스템·네트워크·장치 드라이버 서비스 프로세스.

</details>

```text
[ 마이크로커널 vs 모놀리식 구조 ]
마이크로커널                      모놀리식 커널
┌───────────────────┐             ┌───────────────────┐
│유저 공간 서버     │             │  응용 프로그램     │
│[파일 서버][드라이버│             └─────────┬─────────┘
│      │ IPC 통신  │                       ▼ 시스템 콜
├───────────────────┤             ┌───────────────────┐
│ 마이크로커널      │             │  모놀리식 커널     │
│(프로세스·메모리·IPC│             │(파일·네트워크·드라이버│
└───────────────────┘             └───────────────────┘
```

선의 의미: 가지는 유저 공간 서버와 마이크로커널 간 IPC 통신 경계, 모놀리식은 단일 커널 공간 내 직접 함수 호출 관계

| 구성요소 | 책임 |
|:---|:---|
| 마이크로커널 | 프로세스·메모리 관리·**IPC** 최소 핵심 기능 |
| **사용자 공간 서버** | 파일 시스템·드라이버·네트워크 서비스를 유저 모드에서 격리 실행 |
| **모놀리식 커널** | 파일·네트워크·드라이버를 커널 공간에 통합하여 직접 함수 호출로 처리 |

#### 한줄 요약

- 마이크로커널은 IPC로 유저 공간 서버를 중재하고, 모놀리식 커널은 커널 내부 직접 호출로 모든 서비스를 처리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **컨텍스트 전환 페널티(Context Switch Penalty)**: 마이크로커널에서 I/O 요청 처리 시 응용 프로그램→커널→유저 서버→커널→응용 프로그램의 다중 경계 전환으로 발생하는 지연.

</details>

```text
[ 마이크로커널 IPC 경로 ]               [ 모놀리식 직접 경로 ]
앱 → 시스템 콜 → 마이크로커널           앱 → 시스템 콜 → 모놀리식 커널
   → IPC 메시지 → 유저 서버            (커널 내부 직접 함수 호출로 처리)
   → 유저 서버 처리
   → IPC 결과 → 마이크로커널 → 앱
(다중 컨텍스트 전환 발생)                (단일 컨텍스트 전환)
```

**동작 원리**

1. **마이크로커널 경로**: 시스템 콜 수신 후 마이크로커널이 IPC 메시지로 유저 공간 서버에 요청, 서버 처리 완료 후 IPC로 결과 반환 — 다중 **컨텍스트 전환 페널티** 발생
2. **모놀리식 경로**: 시스템 콜 수신 즉시 커널 내부 함수를 직접 호출하여 처리 — 단일 컨텍스트 전환으로 저지연 처리

#### 한줄 요약

- 마이크로커널은 IPC 다중 전환으로 지연이 크고, 모놀리식은 커널 내부 직접 호출로 저지연 처리

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **seL4**: 마이크로커널의 정확성을 기계 증명(정형 검증)으로 보장한 고신뢰 마이크로커널로, 안전 임계 임베디드 시스템에 적용.

</details>

| 비교 항목 | 모놀리식 커널 (Linux) | 마이크로커널 (QNX, seL4) |
|:---|:---|:---|
| 적용 기준 | 범용 서버·PC, 성능 우선 환경 | 안전 임계 임베디드·의료·항공, 결함 격리 우선 |
| 핵심 특징 | 커널 내부 직접 호출·고성능 | **결함 격리**·유저 공간 서버 재시작 복구 |
| 한계 및 위험 | 단일 드라이버 오류가 커널 패닉으로 전파 | **IPC 오버헤드**로 성능 저하 |

#### 한줄 요약

- 성능 우선 범용 환경은 모놀리식, 결함 격리 우선 안전 임계 환경은 마이크로커널 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **제로 카피 IPC(Zero-Copy IPC)**: 마이크로커널 IPC 시 메모리 복사 없이 공유 메모리 참조로 메시지를 전달하여 IPC 오버헤드를 감소시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 마이크로커널 IPC 다중 컨텍스트 전환으로 성능 저하 | **제로 카피 IPC** 공유 메모리 기반 메시지 전달 적용 | IPC 메시지 복사 오버헤드 감소 |
| 모놀리식 커널에서 서드파티 드라이버 오류로 커널 패닉 발생 | eBPF 샌드박스·검증된 **LKM**만 로드 | 드라이버 오류의 커널 전파 위험 최소화 |
| 안전 임계 시스템에서 단일 컴포넌트 장애가 전체 기능 중단 유발 | **QNX·seL4** 마이크로커널 기반 기능 분리 | 개별 서버 장애가 타 기능에 전파되지 않는 결함 격리 달성 |

#### 한줄 요약

- IPC 오버헤드는 제로 카피로, 드라이버 패닉은 eBPF로, 안전 임계 장애 전파는 마이크로커널로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **커널 아키텍처 선택 기준**: 성능 우선(범용 서버)·결함 격리 우선(안전 임계 시스템)의 요구 우선순위에 따라 모놀리식·마이크로커널·하이브리드를 결정하는 판단 기준.

</details>

- 성능 우선 범용 환경은 **모놀리식(Linux)**, 결함 격리 필수 안전 임계 환경은 **마이크로커널(QNX·seL4)** 선택

#### 한줄 요약

- 고성능 범용 서버는 모놀리식, 결함 격리 필수 안전 임계 시스템은 마이크로커널을 적용
