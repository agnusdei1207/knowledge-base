## 미리 알고가기

- **서비스형 인프라 IaaS(아이에이에스, Infrastructure as a Service)**: 영어 낱말의 첫 글자를 쓴 표기로 서버·저장소·네트워크를 제공하고 소비자가 운영체제부터 관리하는 서비스이다
- **서비스형 플랫폼 PaaS(파스, Platform as a Service)**: 영어 낱말의 첫 글자를 쓴 표기로 운영체제·실행 환경·중간 소프트웨어를 제공하고 소비자가 애플리케이션을 배포하는 서비스이다
- **서비스형 소프트웨어 SaaS(사스, Software as a Service)**: 영어 낱말의 첫 글자를 쓴 표기로 공급자가 운영하는 애플리케이션을 소비자가 설정해 사용하는 서비스이다
- **책임 경계**: 공급자와 소비자가 각각 운영·보호해야 할 계층을 나누는 기준이다
- **제어 범위**: 넓을수록 구성 자유도와 소비자 운영 책임이 함께 늘어난다
- **운영체제 OS(오에스, Operating System)**: 영어 두 낱말의 첫 글자를 쓴 표기로 하드웨어 자원을 관리하고 프로그램 실행 기반을 제공하는 소프트웨어이다
- **런타임·미들웨어**: 프로그램 실행 환경과 애플리케이션 사이의 공통 기능을 제공하는 소프트웨어이다
- **하이퍼바이저·게스트 OS**: 가상 머신을 만들고 제어하는 계층과 그 안에서 실행되는 운영체제이다
- **응용 프로그래밍 인터페이스 API(에이피아이, Application Programming Interface)·데이터베이스 DB(디비, Database)**: 영어 핵심어의 첫 글자를 쓴 약어로 프로그램 간 기능 호출 규약과 구조화된 데이터를 저장·조회하는 저장소를 각각 나타냄
- **책임 매트릭스**: 계층별 운영·보안·증적 담당자를 표로 명시한 문서이다
- **규정 준수 증적**: 보안 통제가 요구대로 수행됐음을 입증하는 기록이다
- **공급자 종속**: 특정 공급자의 기능·형식에 의존해 이전이 어려워지는 상태이다

## Ⅰ. 개요

- 정의/개념: 공급자와 소비자의 **관리 계층 경계**로 서비스를 분류
- **배경/필요성**: 불명확한 **운영·보안 책임**으로 인한 통제 공백 해소

### 쉽게 이해하기 (학습용)
- 필요한 기능보다 어디까지 직접 운영할지 정하는 선택지이다

## Ⅱ. 특징

- 공급자 관리 범위에 따른 **3개 서비스 모델**
- 소비자 제어 범위와 **운영 책임의 비례**
- 상위 관리형 서비스의 **공급자 종속 증가**

### 쉽게 이해하기 (학습용)
- 공급자에 맡기는 계층이 늘면 운영 인력은 줄지만 변경 범위도 좁아진다

## Ⅲ. 아키텍처 및 구성요소

| 계층 | 주요 대상 | 책임 판단 |
|:---|:---|:---|
| 물리·가상화 | 가상 서버와 하이퍼바이저 | 모든 모델에서 공급자가 운영함 |
| OS·런타임·미들웨어 | 게스트 OS와 웹 서버 및 DB | IaaS는 소비자, 나머지는 공급자임 |
| 애플리케이션 | 업무 로직과 화면 및 API | SaaS는 공급자, 나머지는 소비자임 |
| 데이터·계정 | 업무 데이터와 접근 권한 | 소비자가 분류·권한·적법한 이용을 책임짐 |
| 책임 매트릭스 | 계층별 운영과 보안 및 증적 | 계약과 문서로 책임자를 확정함 |

```text
  요구분석
      ↓
  경계설정
      ↓
  모델선택
      ↓
  책임확정
      ↓
  통제검증
```

> 요약: 서비스 계층을 따라 소비자 제어와 공급자 운영 경계가 반대이다

### 쉽게 이해하기 (학습용)
- 계층마다 공급자와 소비자 중 누가 운영을 맡는지 확정한다

## Ⅳ. 원리 및 절차 흐름도

```text
요구분석
   ↓
경계설정
   ↓
모델선택
   ↓
책임확정
   ↓
통제검증
```

| 절차 | 설명 |
|:---|:---|
| **요구분석** | 규제와 운영 역량을 업무별로 확인함 |
| **경계설정** | 직접 제어할 인프라와 플랫폼을 구분함 |
| **모델선택** | 요구 수준에 적합한 서비스 모델을 정함 |
| **책임확정** | 계정과 데이터의 관리 주체를 문서화함 |
| **통제검증** | 계약과 실제 클라우드 설정의 일치를 검증함 |

> 요약: 제어와 운영 책임을 대조해 모델을 결정하고 통제를 검증한다

### 쉽게 이해하기 (학습용)
- 관리할 일과 맡길 일을 나눈 뒤 모델과 책임표를 정한다

## Ⅴ. 종류 및 비교

| 비교축 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|
| 적용 기준 | 자체 OS 구성·이전 필요 | 플랫폼 관리 인력 절감 | 유지보수 비용 최소화 |
| 핵심 특징 | 가상 컴퓨팅·저장소·네트워크 | 관리형 런타임·미들웨어 | 공급자 운영 애플리케이션 |
| 한계 | 인프라 운영·보안 책임 | 런타임·플랫폼 제약 | 맞춤화·데이터 이동성 제약 |

> 요약: 상위 모델로 갈수록 완제품이 제공되고 변경 범위는 줄어든다

### 쉽게 이해하기 (학습용)
- IaaS는 기반부터 운영하고 PaaS는 앱을 배포하며 SaaS는 완성 기능을 사용한다

## Ⅵ. 실무 사례

1. 웹 서버를 **IaaS로 이전**, OS 패치 책임 확인

### 쉽게 이해하기 (학습용)
- IaaS 이전은 OS 패치 책임과 준수율을 함께 확인한다

## Ⅶ. 결론

- 클라우드 활용과 운영 통제를 균형 있게 확보하기 위해 **필요 제어 범위·팀의 운영 역량·공급자 책임 경계**를 검토하고, 업무에 맞는 IaaS·PaaS·SaaS를 선택한다

### 쉽게 이해하기 (학습용)
- 필요한 통제와 팀의 운영 역량에 책임 경계가 맞는 모델을 선택한다
