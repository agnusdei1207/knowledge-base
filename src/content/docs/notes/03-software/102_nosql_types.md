## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NoSQL 4대 유형**: Key-Value(단순 키값 매핑), Document(JSON/BSON 문서 중첩), Wide-Column(행-컬럼 패밀리 희소 행렬), Graph(노드-간선 관계 순회)로 분류되는 비관계형 데이터베이스.
- **엄격한 스키마 및 분산 확장성 한계(Schema Rigidity & Scalability Limit)**: RDBMS의 정형 테이블 구조와 복잡한 조인 연산으로 인해 대규모 비정형 데이터 수용과 무중단 수평 확장이 제한되는 문제.

</details>

- 정의/개념: 관계형 스키마와 수평 확장의 한계를 극복하기 위해 **Key-Value, Document, Wide-Column, Graph 등 4대 특화 모델을 제공**하는 비관계형 데이터베이스
- 배경/필요성: 대규모 비정형 데이터 폭증 및 복잡한 관계 순회 환경에서 RDBMS의 **엄격한 스키마, 조인 연산 병목 및 분산 확장성 한계** 직면

#### 한줄 요약

- 데이터 구조와 접근 패턴에 따라 4대 NoSQL 모델을 적재적소에 선택하여 수평 확장성과 고성능을 달성

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가변 스키마(Schema-less / Dynamic Schema)**: 사전 DDL 정의 없이 새로운 필드를 자유롭게 추가하고 레코드마다 서로 다른 구조를 가질 수 있는 유연성.
- **폴리글랏 퍼시스턴스(Polyglot Persistence)**: 단일 DB에 모든 데이터를 넣지 않고 용도에 맞추어 RDBMS, 캐시, 문서 DB, 그래프 DB를 혼용 구축하는 아키텍처 사상.

</details>

- 비정형 데이터의 유연한 확장을 보장하는 **가변 스키마(Schema-less) 지원**
- 노드 증설을 통해 선형적으로 용량을 확장하는 **분산 수평 확장(Scale-Out) 최적화**
- 서비스 도메인 특성에 맞추어 최적의 엔진을 조합하는 **폴리글랏 퍼시스턴스(Polyglot Persistence)**

#### 한줄 요약

- 가변 스키마와 수평 확장성을 바탕으로 데이터 성격에 최적화된 비관계형 모델을 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **4대 데이터 모델**: Key-Value(Redis), Document(MongoDB), Wide-Column(Cassandra), Graph(Neo4j).

</details>

```text
[ NoSQL 4대 데이터 모델 아키텍처 분류도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      NoSQL 4대 데이터 모델 분류                        │
 ├─────────────────────┬───────────────────┬──────────────────────────────┤
 │ 1. Key-Value Store  │ 2. Document Store │ 3. Wide-Column / Graph       │
 ├─────────────────────┼───────────────────┼──────────────────────────────┤
 │ • [Key] ──► [Value] │ • [JSON / BSON]   │ • Wide-Column: Row-Column Fam│
 │ • Redis, DynamoDB   │   - 중첩 배열/객체│   - Cassandra, HBase         │
 │ • 초고속 캐시/세션  │ • MongoDB, Couch  │ • Graph: Node - Edge         │
 │                     │ • 카탈로그/콘텐츠 │   - Neo4j (관계 순회)        │
 └─────────────────────┴───────────────────┴──────────────────────────────┘
```

선의 의미: 데이터 복잡도와 조회 패턴에 따라 키값, 문서, 와이드 컬럼, 그래프 저장소로 분화된 구조.

| 구성요소 | 책임 |
|:---|:---|
| Key-Value Store | 유일 키(Key) 기반으로 값(Value)을 저장하여 **$O(1)$ 초고속 캐시 및 세션 처리** |
| Document Store | JSON/BSON 형태의 중첩 계층 구조를 저장하여 **도메인 객체 및 상품 카탈로그 관리** |
| Wide-Column Store | 행 키와 동적 컬럼 패밀리 구조로 **대규모 시계열/IoT 로그 데이터 쓰기 분산** |
| Graph Store | 노드(Node)와 간선(Edge)의 그래프 구조로 **소셜 네트워크 및 다단계 추천 경로 순회** |

#### 한줄 요약

- 키값(캐시), 문서(카탈로그), 컬럼(시계열), 그래프(관계 순회)의 4대 모델로 역할을 분담

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NoSQL 데이터 모델 선정 5단계 파이프라인**: 접근 패턴 분석 $\to$ 관계 복잡도 판정 $\to$ 일관성 수준 평가 $\to$ 엔진 모델 선택 $\to$ 분산 검증.

</details>

```text
[ NoSQL 데이터 모델 선정 및 아키텍처 설계 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 접근 패턴 식별: 단건/범위/관계순회   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 데이터 관계 분석: 중첩/희소/그래프  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 일관성 요구 판정: ACID vs BASE      │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 최적 NoSQL 엔진 모델 선택           │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 수평 분산 및 장애 복구 검증        │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 접근 패턴 식별: 키 기반 단순 조회인지, 범위 검색인지, 다단계 관계 탐색인지 쿼리 패턴을 분석.
2. 데이터 관계 분석: 계층적 중첩 문서인지, 희소한 대량 컬럼인지, 네트워크 그래프인지 데이터 구조를 평가.
3. 일관성 요구 판정: 엄격한 트랜잭션(ACID)이 필수적인지 최종 일관성(BASE)으로 충분한지 판정.
4. 모델 선택: 분석 결과를 토대로 Key-Value(Redis), Document(MongoDB), Column(Cassandra), Graph(Neo4j) 중 선택.
5. 분산 검증: 샤딩 및 레플리케이션 환경에서 부하 분산과 장애 복구(Failover) 성능을 검증.

#### 한줄 요약

- 접근 패턴 $\to$ 관계 분석 $\to$ 일관성 판정 $\to$ 모델 선택 $\to$ 분산 검증의 5단계 파이프라인

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **4대 NoSQL 특성 비교**: Key-Value(단순 고속), Document(유연 중첩), Wide-Column(대규모 쓰기), Graph(관계 탐색).

</details>

| 구분 | Key-Value Store | Document Store | Wide-Column Store | Graph Store |
|:---|:---|:---|:---|:---|
| **적용 기준** | 고속 세션, 캐시, 단순 룩업 | 상품 정보, 주문서, 콘텐츠 | IoT 센서, 대규모 로그, 시계열 | 소셜 친구 추천, 사기 탐지(FDS) |
| **핵심 특징** | **단순 Key-Value 매핑, 최고속도** | **JSON/BSON 중첩 문서 단위 인덱싱** | **Row Key 및 컬럼 패밀리 희소 행렬** | **Node, Edge 기반 관계 순회 알고리즘** |
| **한계** | 값 내부 조건 검색 불가 | 복합 다중 문서 트랜잭션 오버헤드 | 복잡한 조인 및 Ad-hoc 조회 제약 | 대규모 분산 클러스터링 구성 난이도 |

#### 한줄 요약

- 캐시는 Key-Value, 콘텐츠는 Document, 대용량 로그는 Wide-Column, 연결 관계는 Graph Store를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NoSQL 반정규화 안티패턴(Normalization Trap)**: NoSQL에 RDBMS 방식으로 정규화를 적용하여 애플리케이션 단에서 수많은 조인 쿼리를 유발하는 설계 오류.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| NoSQL에 정규화 적용으로 애플리케이션 N+1 조회 폭증 | **접근 패턴에 맞추어 문서 내포(Embedding) 및 의도적 중복 설계** | 단일 쿼리로 데이터 조회 완결 |
| NoSQL 도입 후 트랜잭션 미지원으로 인한 데이터 정합성 파괴 | **핵심 결제 데이터는 RDBMS에 유지하는 Polyglot Persistence 구축** | 정합성과 성능의 영역별 분리 달성 |
| 특정 파티션 키로 트래픽이 몰리는 핫스팟(Hotspot) 발생 | **복합 파티션 키(Salt 추가 / 시간 해시) 설계로 균등 분산** | 노드 부하 편향 완화 |

#### 한줄 요약

- 쿼리 맞춤 내포 설계, 폴리글랏 아키텍처 도입, 복합 파티션 키 적용으로 안정적 NoSQL을 운용

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **폴리글랏 데이터 플랫폼(Polyglot Data Platform)**: RDBMS와 4대 NoSQL의 장점을 결합하여 서비스별 최적의 데이터 저장소를 제공하는 차세대 아키텍처.

</details>

- **NoSQL** 빅데이터와 클라우드 네이티브 환경에서 RDBMS의 한계를 극복하는 필수 인프라이며, 4대 모델의 특성을 명확히 이해하고 비즈니스 쿼리 패턴에 부합하는 최적의 엔진을 배치해야 함

#### 한줄 요약

- 4대 NoSQL 모델의 장점을 활용하고 폴리글랏 아키텍처를 구축하여 대규모 비정형 데이터를 효율적으로 처리
