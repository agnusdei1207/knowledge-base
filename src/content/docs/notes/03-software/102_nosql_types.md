## 미리 알고가기

- **비관계형 데이터베이스 (Not Only SQL, NoSQL)**: 다양한 모델로 데이터를 저장함
- **자바스크립트 객체 표기법 (JavaScript Object Notation, JSON)**: 문서 데이터를 표현함
- **문서형 (Document Store)**: 문서 단위 객체를 저장함
- **키값형 (Key-Value Store)**: 고유 키로 값을 조회함
- **컬럼형 (Wide-Column Store)**: 행 키 아래 컬럼 묶음을 저장함
- **그래프형 (Graph Database)**: 정점·간선으로 관계를 저장함
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **95백분위 지연 (95th Percentile Latency, p95)**: 요청 95%가 완료되는 지연 기준임
- **스키마(Schema)**: 데이터의 필드·형식·관계 등 논리 구조를 정의한 명세임
- **파티션(Partition)**: 분산 저장과 처리를 위해 데이터를 나눈 논리 단위임
- **복제(Replication)**: 같은 데이터의 사본을 여러 노드에 유지하는 기술임
- **일관성(Consistency)**: 여러 읽기와 사본에서 데이터 규칙과 최신 상태가 유지되는 성질임
- **정점(Vertex)**: 그래프에서 사람·상품 같은 개체를 나타내는 요소임
- **간선(Edge)**: 두 정점 사이의 관계와 방향을 나타내는 요소임

## Ⅰ. 개요

- **정의/개념**: 비관계형 모델로 데이터를 저장·조회함
- **배경/필요성**: 가변 구조·분산 접근으로 NoSQL 선택 필요

### 쉽게 이해하기 (학습용)
- 모든 자료를 같은 표에 넣지 않고 문서·사물함·열 묶음·관계망에 맞춰 보관하는 방식임

## Ⅱ. 특징

- 저장 모델에 따라 조회 방식과 확장 방식이 함께 달라진다.
- 애플리케이션이 스키마 검증과 버전 호환을 관리한다.
- 지원 일관성 범위에 맞춰 트랜잭션 경계를 정해야 한다.
- 조회 패턴과 모델이 다르면 우회 로직이 늘어난다.

### 쉽게 이해하기 (학습용)
- 데이터 모델별 전용 질의와 일관성 및 파티션 규칙을 설계해야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 모델 | 문서와 키값 및 컬럼과 그래프 단위를 정함 |
| 파티션 기준 | 분산 키로 데이터 위치와 편중을 정함 |
| 복제 정책 | 사본 수와 읽기 및 복구 수준을 정함 |
| 질의 방식 | 모델별 직접 지원할 조회를 정함 |

```text
  모델선택
      ↓
  기준수립
      ↓
  복제설계
      ↓
  조회정의
```

> 요약: 데이터 모델과 파티션 및 복제가 저장과 조회 경로를 정함

### 쉽게 이해하기 (학습용)
- 데이터 모양과 핵심 조회 방식에 맞춰 모델·파티션·복제 정책을 함께 결정함

## Ⅳ. 원리 및 절차 흐름도

```text
  패턴식별
      ↓
  모델선택
      ↓
  정책설계
      ↓
  오류검증
```

| 절차 | 설명 |
|:---|:---|
| 패턴식별 | 단건과 객체 및 범위와 관계 조회를 식별함 |
| 모델선택 | 핵심 조회를 직접 지원하는 모델을 선택함 |
| 정책설계 | 파티션과 복제 및 일관성 수준을 정함 |
| 데이터검증 | 지연과 편중 및 트랜잭션 제약을 검증함 |

> 요약: 조회 패턴으로 모델을 정하고 분산 정책을 검증함

### 쉽게 이해하기 (학습용)
- 가장 자주 수행하는 조회를 직접 지원하는 모델을 정한 뒤 지연·편중·일관성 비용을 검증함

## Ⅴ. 종류 및 비교

| 비교축 | 문서형 | 키값형 | 컬럼형 | 그래프형 |
|:---|:---|:---|:---|:---|
| 핵심 특징 | 문서 내부 필드를 함께 저장함 | 고유 키로 하나의 값을 조회함 | 행 키 아래 넓은 열 묶음을 저장함 | 정점과 간선의 경로를 탐색함 |
| 적용 기준 | 가변 속성 객체 조회 | 빠른 단건 조회 | 분산 쓰기와 열 범위 조회 | 다단계 관계 탐색 |
| 주요 위험 | 큰 문서와 필드 검색 비용 | 키 외 검색 기능 부족 | 키 편중과 확산 조회 | 탐색 분기와 깊이 증가 |

> 요약: 객체와 단건 및 범위와 관계 조회에 맞춰 유형을 선택함

### 쉽게 이해하기 (학습용)
- 문서형은 객체 구조를, 키값형은 단건 접근을, 컬럼형은 넓은 행 범위를, 그래프형은 관계 경로를 직접 표현함

## Ⅵ. 실무 사례

1. 카탈로그는 가변 속성을 저장하고 조회 지연을 확인함
2. 이상 거래 탐지는 다단계 관계를 탐색하고 질의 시간을 확인함

### 쉽게 이해하기 (학습용)
- 상품 카탈로그는 상품마다 다른 속성을 한 문서에 담아 구조 변경과 객체 조회를 단순화함
- 이상 거래 탐지는 계좌·기기·거래를 정점과 간선으로 연결해 여러 단계의 의심 경로를 직접 탐색함

## Ⅶ. 결론

- 핵심 조회·분포·일관성에 맞는 NoSQL 유형 선택

### 쉽게 이해하기 (학습용)
- NoSQL 유형은 핵심 조회의 직접 표현과 분산 비용 허용 한도로 결정함
