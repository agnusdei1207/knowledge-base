## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이퍼바이저(Hypervisor, VMM)**: 물리 하드웨어 자원을 추상화하여 복수의 가상 머신(VM)에 격리 할당하고 VM 간 자원 충돌을 중재하는 소프트웨어 계층.
- **Type 1 (Bare-Metal) 하이퍼바이저**: 호스트 OS 없이 물리 하드웨어 위에 직접 설치되어 VM을 관리하는 방식으로 ESXi·Hyper-V·KVM이 대표적.
- **Type 2 (Hosted) 하이퍼바이저**: 호스트 OS 위에 응용 프로그램으로 설치되어 VM을 관리하는 방식으로 VirtualBox·VMware Workstation이 대표적.

</details>

- 정의/개념: 물리 하드웨어를 추상화하여 복수의 VM을 격리 구동하는 **하이퍼바이저(VMM)** 및 호스트 OS 의존 여부에 따른 **Type 1 / Type 2** 구분
- 배경/필요성: 물리 서버 1대에 OS 1개 운영 시 CPU·메모리 유휴가 심각하므로, **하드웨어 가상화 기반 자원 이용률 극대화 체계 필수**

#### 한줄 요약

- 물리 서버 자원 이용률 극대화를 위해 하이퍼바이저가 복수의 VM에 가상 자원을 격리 할당하는 가상화 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VM Exit / VM Entry**: 게스트 OS의 특권 명령 실행 시도 시 하드웨어가 하이퍼바이저로 제어권을 이전(VM Exit)하고, 처리 완료 후 게스트로 반환(VM Entry)하는 컨텍스트 전환.
- **하드웨어 지원 가상화(Hardware-Assisted Virtualization)**: Intel VT-x·AMD-V 등 CPU가 가상화를 하드웨어 수준에서 지원하여 소프트웨어 에뮬레이션 오버헤드를 감소시키는 기술.

</details>

- VM별 독립 가상 자원 할당으로 단일 VM 장애가 타 VM에 전파되지 않는 **격리 경계** 형성
- **Intel VT-x / AMD-V** 하드웨어 가상화로 VM Exit/Entry 오버헤드 최소화
- 호스트 OS 직결 여부에 따른 **Type 1 고성능**과 **Type 2 개발 편의성** 간 성능 차이

#### 한줄 요약

- VM별 격리 경계를 형성하고 하드웨어 가상화로 VM Exit/Entry 오버헤드를 최소화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 CPU (vCPU)**: 하이퍼바이저가 게스트 OS에 논리 프로세서로 제공하는 가상 CPU 단위.
- **확장 페이지 테이블(EPT/NPT)**: 게스트 가상 주소→게스트 물리 주소→호스트 물리 주소의 2단계 변환을 하드웨어가 직접 수행하여 주소 변환 오버헤드를 감소시키는 메모리 가상화 기술.

</details>

```text
[ Type 1 vs Type 2 하이퍼바이저 구조 ]
Type 1 (Bare-Metal)         Type 2 (Hosted)
┌───────────────┐            ┌───────────────┐
│  VM1  │  VM2  │            │  VM1  │  VM2  │
└───────┴───────┘            └───────┴───────┘
│ Type 1 하이퍼바이저 │       │ Type 2 하이퍼바이저│
└───────────────┘            └───────────────┘
│  물리 하드웨어  │           │   호스트 OS    │
└───────────────┘            └───────────────┘
                             │  물리 하드웨어  │
                             └───────────────┘
```

선의 의미: 위아래 계층 관계는 하이퍼바이저와 하드웨어·VM 간 제어 권한 흐름

| 구성요소 | 책임 |
|:---|:---|
| 가상 머신 (VM) | 게스트 OS·응용 프로그램을 격리 실행하는 가상 환경 |
| **Type 1 하이퍼바이저** | 물리 하드웨어에 직접 설치하여 VM 자원 직접 할당·중재 |
| **Type 2 하이퍼바이저** | 호스트 OS 위 응용 프로그램으로 VM 자원을 호스트 OS 경유 할당 |
| vCPU / EPT | 게스트 CPU 가상화·2단계 메모리 주소 변환 하드웨어 지원 |

#### 한줄 요약

- Type 1은 물리 하드웨어 직접 관리로 고성능을, Type 2는 호스트 OS 경유로 개발 편의성을 제공

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **트랩 앤 에뮬레이트(Trap-and-Emulate)**: 게스트 OS의 특권 명령 실행 시도 시 하드웨어 트랩으로 실행을 중단하고 하이퍼바이저가 해당 명령을 에뮬레이션하는 기본 가상화 메커니즘.

</details>

```text
게스트 OS 일반 연산 실행
   │
   ▼
1. 특권 명령 실행 시도 (I/O·인터럽트 제어 등)
   │
   ▼
2. VM Exit: 하드웨어 트랩 발생 → 하이퍼바이저로 제어권 이전
   │
   ▼
3. 하이퍼바이저 중재 (Trap-and-Emulate)
├─ Type 1: 물리 하드웨어 직접 접근
└─ Type 2: 호스트 OS를 경유하여 처리
   │
   ▼
4. VM Entry: 처리 결과를 게스트 레지스터에 반영 후 재개
```

**동작 원리**

1. **특권 명령 시도**: 게스트 OS가 CPU 제어·I/O 등 하이퍼바이저 권한의 특권 명령을 실행 시도
2. **VM Exit**: 하드웨어 트랩으로 게스트 실행이 중단되고 하이퍼바이저로 제어권 이전
3. **중재 및 에뮬레이션**: 하이퍼바이저가 요청을 처리하고 물리 하드웨어 자원을 대신 접근
4. **VM Entry**: 처리 결과를 게스트 레지스터에 반영하고 게스트 실행 재개

#### 한줄 요약

- 게스트의 특권 명령 시도 시 VM Exit으로 하이퍼바이저가 중재하고 VM Entry로 게스트에 반환

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **KVM(Kernel-based Virtual Machine)**: 리눅스 커널 모듈로 구현된 Type 1 하이퍼바이저로, 커널이 직접 VM을 관리하는 오픈소스 가상화 솔루션.

</details>

| 비교 항목 | Type 1 (ESXi, Hyper-V, KVM) | Type 2 (VirtualBox, VMware Workstation) | 컨테이너 (Docker, LXC) |
|:---|:---|:---|:---|
| 적용 기준 | 고성능·고가용성 클라우드 서버 인프라 | 개발·테스트 환경 간편 구성 | 경량 마이크로서비스·클라우드 네이티브 |
| 핵심 특징 | 물리 하드웨어 직접 제어·낮은 오버헤드 | 호스트 OS 경유·높은 설치 편의성 | 호스트 OS 커널 공유·VM 없는 경량 격리 |
| 한계 및 위험 | 설치·관리 복잡성 높음 | 호스트 OS 이중 거침으로 성능 오버헤드 증가 | 커널 공유로 호스트 OS 취약점 노출 위험 |

#### 한줄 요약

- 고성능 클라우드는 Type 1, 개발 편의는 Type 2, 경량 마이크로서비스는 컨테이너 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SR-IOV(Single Root I/O Virtualization)**: PCIe NIC을 하드웨어에서 복수의 가상 함수(VF)로 분할하여 VM이 하이퍼바이저 개입 없이 NIC에 직접 접근하는 I/O 패스스루 기술.
- **오버서브스크립션(Oversubscription)**: 물리 자원 총량을 초과하여 vCPU·가상 메모리를 VM에 할당하는 방식으로, 실제 동시 사용량이 낮을 때 이용률을 향상시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하이퍼바이저 개입으로 네트워크 I/O 지연 증가 | **SR-IOV** 패스스루로 VM이 NIC에 직접 접근 | 네트워크 I/O 오버헤드 감소 및 베어메탈 수준 지연 달성 |
| 2단계 메모리 주소 변환 오버헤드 발생 | **EPT/NPT** 하드웨어 지원 활성화 | 소프트웨어 페이지 워크 비용 제거 |
| **오버서브스크립션** 과잉 시 자원 경합으로 전체 VM 성능 저하 | vCPU Quota·cgroups 기반 최대 자원 한도 설정 | VM 간 자원 경합 방지 및 성능 안정성 확보 |

#### 한줄 요약

- 네트워크 병목은 SR-IOV로, 메모리 주소 변환 오버헤드는 EPT/NPT로, 자원 경합은 vCPU Quota로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상화 아키텍처 선택 기준**: 성능·격리 수준·관리 복잡성·경량화 요구에 따라 Type 1·Type 2·컨테이너를 결정하는 판단 기준.

</details>

- 고성능 클라우드 인프라는 **Type 1 (KVM/ESXi)**, 개발 환경은 **Type 2**, 경량 마이크로서비스는 **컨테이너** 선택

#### 한줄 요약

- 성능·격리 우선이면 Type 1, 설치 편의 우선이면 Type 2, 경량·확장성 우선이면 컨테이너를 적용
