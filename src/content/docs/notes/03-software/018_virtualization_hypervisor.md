## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이퍼바이저(Hypervisor, VMM)**: 물리 하드웨어 위에 군림하며 짭드웨어(가상 자원)를 찍어내고, 여러 게스트 OS들이 싸우지 않게 멱살 잡고 교통정리를 하는 절대자(소프트웨어 레이어)이다.
- **Type 1 (Bare-Metal) 하이퍼바이저**: 거추장스러운 기존 OS를 싹 다 치워버리고 쌩 하드웨어 위에 다이렉트로 올라타서 깡성능을 쥐어짜 내는 실전 압축 하이퍼바이저이다.
- **Type 2 (Hosted) 하이퍼바이저**: 윈도우나 맥 같은 기존 호스트 OS 위에 응용 프로그램(앱)처럼 얹혀살면서 가상머신을 띄우는, 개발자들 장난감용 하이퍼바이저이다.

</details>

- 정의: 하드웨어 자원을 추상화해서 복수의 가짜 컴퓨터(가상머신)를 멱살 잡고 격리 구동시키는 **하이퍼바이저(VMM)**와 그 구현 방식인 **Type 1 / Type 2**
- 배경: 서버 한 대에 OS 하나만 돌리면 CPU랑 램이 맨날 팽팽 놀아서 **자원 유휴**와 낭비가 뼈아프기 때문

#### 한줄 요약

- 컴퓨터 한 대를 여러 대인 것처럼 쪼개주는 마법사(하이퍼바이저)와 쌩 하드웨어에 붙냐(Type 1), OS 위에 붙냐(Type 2)의 차이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VM Exit / VM Entry**: 게스트 OS가 나대면서 위험한 특권 명령어를 치면 하이퍼바이저로 통제권이 넘어가고(VM Exit), 처리 끝나면 다시 게스트로 돌려주는(VM Entry) 컨텍스트 스위칭 굴레이다.
- **하드웨어 지원 가상화(Hardware-Assisted Virtualization)**: 인텔 VT-x나 AMD-V처럼, 하이퍼바이저가 소프트웨어로 치던 똥꼬쇼를 CPU 하드웨어 단에서 다이렉트로 때려 박아 속도를 떡상시키는 치트키이다.

</details>

- 게스트 OS별로 자원과 런타임을 철저하게 분리해서 한 놈이 죽어도 옆 놈은 살게 하는 **격리 경계** 구축.
- 소프트웨어 똥꼬쇼를 버리고 **Intel VT-x / AMD-V** 하드웨어 가상화로 오버헤드를 박살 냄.
- 호스트 OS를 패스하고 하드웨어에 직접 꽂히는 **Type 1 (고성능)**과 호스트 OS를 거치는 **Type 2 (개발 편의성)**의 성능 격차가 큼.

#### 한줄 요약

- 완벽한 격리를 제공하며, 하드웨어의 도움(VT-x)을 받아 VM Exit/Entry 오버헤드를 씹어 먹는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 CPU (vCPU)**: 하이퍼바이저가 게스트 OS한테 "이게 진짜 네 CPU야"라고 사기 쳐서 던져주는 논리적 가짜 코어 단위이다.
- **확장 페이지 테이블 (EPT/NPT)**: 가상 주소를 물리 주소로 두 번이나 번역하는 개짓거리를, 하드웨어가 직접 투패스로 뚫어버려서 주소 변환 오버헤드를 삭제하는 메모리 가상화 꼼수이다.

</details>

```text
[ 하이퍼바이저 타입별 십자포화 아키텍처 ]
      [ Type 1 (Bare-Metal) ]          [ Type 2 (Hosted) ]
        ┌─────────────┐                  ┌─────────────┐
        │ VM1 │  VM2  │                  │ VM1 │  VM2  │
        └──────┬──────┘                  └──────┬──────┘
               ▼                                ▼
     [ Type 1 하이퍼바이저 ]           [ Type 2 하이퍼바이저 ]
      (OS 없이 하드웨어 직결)                   │
               │                           [ 호스트 OS ]
               │                         (윈도우/리눅스 등)
               ▼                                ▼
        [ 쌩 물리 하드웨어 ]              [ 쌩 물리 하드웨어 ]
```

| 구성요소 | 책임 |
|:---|:---|
| 가상머신 (VM) | 하이퍼바이저가 깎아준 가짜 하드웨어 위에서 지가 진짜인 줄 알고 도는 게스트 OS 덩어리 |
| **Type 1 하이퍼바이저** | 깡 하드웨어 위에 직접 알박기해서 VM들의 자원을 다이렉트로 멱살 잡고 꽂아주는 대장 |
| **Type 2 하이퍼바이저** | 호스트 OS 위에 응용 프로그램처럼 얹혀살면서, OS 눈치 보며 VM 자원을 구걸하는 세입자 |
| 호스트 OS | Type 2 환경에서 하드웨어를 쥐고 흔들며, 하이퍼바이저의 I/O 요청을 대신 처리하는 주인님 |
| 물리 하드웨어 | 가상화의 근본이 되는 진짜 CPU, 램, 디스크 장비 |

#### 한줄 요약

- Type 1은 OS 없이 쌩 하드웨어와 맞짱 뜨고, Type 2는 기존 호스트 OS 위에 기생해서 구동된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **트랩 앤 에뮬레이트 (Trap-and-Emulate)**: 게스트 OS가 건방지게 시스템의 핵심(특권 명령어)을 건드리려 할 때, 하드웨어가 예외(Trap)를 띄워 멈추고 하이퍼바이저가 대신 실행한 척 사기(Emulate)를 치는 근본 동작이다.

</details>

```text
[ 가상화 런타임 제어 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 게스트 OS 특권 명령 시도  │
│ (나대면서 CPU 코어 통제 시도)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 트랩 발동 & VM Exit       │
│ (하드웨어가 멱살 잡고 멈춤)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 하이퍼바이저 중재 및 모사 │
│ (Trap-and-Emulate 똥꼬쇼)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 상태 복구 & VM Entry      │
│ (결과만 던져주고 다시 실행)  │
└──────────────────────────────┘
```

### 동작 원리

1. 게스트 명령 실행: 평범한 연산은 지가 알아서 짭 CPU에서 돌림.
2. VM Exit: 게스트가 민감한 특권 명령을 찌르는 순간, 하드웨어가 트랩을 걸고 통제권을 넘김(**VM Exit**).
3. 자원 중재 (Emulation): 하이퍼바이저가 진짜 하드웨어를 대신 건드려서 결과를 만들어냄 (Type 1은 다이렉트, Type 2는 호스트 OS에 짬처리).
4. VM Entry: 결과를 게스트 OS 레지스터에 발라주고, 아무 일 없었던 것처럼 다시 코드로 통제권을 돌려줌(**VM Entry**).

#### 한줄 요약

- 게스트가 선을 넘으면 하드웨어가 멈추고(Exit), 하이퍼바이저가 수습한 뒤 돌려보낸다(Entry).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **KVM (Kernel-based Virtual Machine)**: 평범한 리눅스 커널을 통째로 Type 1 하이퍼바이저로 마개조해 버리는 궁극의 오픈소스 가상화 모듈이다.

</details>

| 비교 항목 | **Type 1** (ESXi, Hyper-V, KVM) | **Type 2** (VirtualBox, VMware Workstation) | **컨테이너** (Docker, LXC) |
|:---|:---|:---|:---|
| 뼈대 구조 | 쌩 하드웨어 위에 대장이 직접 올라탐 | 호스트 OS 위에 앱처럼 얹힘 | 하이퍼바이저 없이 **호스트 OS 커널 공유** |
| 무거운 정도 | 게스트 OS를 통째로 띄워야 해서 무거움 | 호스트 OS + 게스트 OS까지 띄워 개무거움 | OS 부팅 스킵하고 프로세스만 띄워 깃털처럼 가벼움 |
| 성능/오버헤드 | 쌩 하드웨어를 다이렉트로 갈궈 성능 짱 | OS를 두 번 거쳐서 오버헤드가 하늘을 찌름 | 가상화 오버헤드가 0(Zero)에 수렴하는 네이티브 속도 |
| 최고존엄 용도 | AWS, 데이터센터 같은 빡센 클라우드 서버 | 개발자 PC에서 테스트 환경 잠깐 띄울 때 | 마이크로서비스(MSA), 무한 확장 클라우드 네이티브 앱 |

#### 한줄 요약

- 성능 끝판왕은 Type 1, PC 개발용은 Type 2, 초경량 클라우드 네이티브는 컨테이너다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SR-IOV (Single Root I/O Virtualization)**: 랜카드(NIC) 하나를 하드웨어 단에서 여러 개의 짭 랜카드로 쪼개서, VM이 하이퍼바이저 안 거치고 다이렉트로 I/O를 꽂아버리는 미친 패스스루(Pass-Through) 기술이다.
- **오버서브스크립션 (Oversubscription)**: 실제 CPU 코어는 10개인데, VM들한테는 "너네 다 1코어씩 써" 하고 vCPU를 30개씩 뻥튀기해서 팔아먹는 얄팍한 초과 할당 상술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하이퍼바이저가 네트워크 I/O마다 끼어들어서 트래픽 핑이 튀고 밀림 | **SR-IOV** 갈겨서 하이퍼바이저 패스하고 랜카드에 다이렉트로 꽂음 | I/O 오버헤드를 삭제해서 베어메탈급 레이턴시 확보 |
| 가상 메모리를 진짜 메모리로 2번이나 번역하느라 MMU가 뺑이 침 | 하드웨어 칩셋 단에서 2단 번역을 지원하는 **EPT/NPT** 기능 활성화 | 페이지 워크 비용을 하드웨어로 찍어 누르고 성능 떡상 |
| **오버서브스크립션** 뻥튀기를 쳐놔서 VM들이 동시에 발작하면 멈춤 | 물리 한계치 계산해서 cgroups나 vCPU Quota로 멱살 잡고 컷침 | 스레싱과 자원 경합으로 호스트 전체가 뻗는 참사 방지 |

#### 한줄 요약

- 네트워크 병목은 SR-IOV로 우회하고, 메모리 병목은 EPT로 박살 내며, 뻥튀기 상술은 쿼터로 통제하라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상화 아키텍처 선택 기준 (Virtualization Selection Criteria)**: 하드웨어 다이렉트 제어냐, 개발 편의성이냐, 커널 공유냐를 따져서 Type 1 / 2 / 컨테이너를 가르는 설계 잣대이다.

</details>

- **가상화 아키텍처 선택 기준** 원칙에 따라, 빡센 클라우드 인프라는 **Type 1 (KVM/ESXi)**, 개발 환경은 **Type 2**, 경량 아키텍처는 **컨테이너** 채택 기조 확립함

#### 한줄 요약

- 하드웨어를 영혼까지 쥐어짜야 하면 Type 1, 가볍고 유연하게 띄우려면 컨테이너로 가라.
