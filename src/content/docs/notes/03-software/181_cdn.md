## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CDN (Content Delivery Network)**: 지리적으로 분산된 엣지 서버(Edge PoP)에 정적/동적 웹 콘텐츠를 캐싱하여 사용자에게 최단 경로로 전송하는 분산 네트워크.
- **Anycast BGP**: 전 세계 수백 개 엣지 서버에 단일 가상 IP를 공유하고 BGP 최단 경로 엣지 PoP로 트래픽을 자동 라우팅하는 기술.

</details>

- 정의/개념: 지리적으로 분산된 엣지 서버(Edge PoP)에 **정적·동적 콘텐츠를 캐싱하여 사용자와 가장 가까운 위치에서 초저지연 전송하는 분산 네트워크**
- 배경/필요성: 단일 원본 서버(Origin)로 모든 웹 트래픽 직접 유입 시 발생하는 **대륙 간 네트워크 왕복 지연(RTT), 원본 대역폭 비용 폭증 및 트래픽 스파이크 시 서버 다운 한계**

#### 한줄 요약
- 전 세계 엣지 PoP 캐싱과 Anycast 라우팅을 통해 응답 속도를 극대화하고 원본 부하를 절감한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Origin Shield**: 엣지 PoP들과 원본 서버 사이에 중간 캐시 계층을 두어 캐시 미스 시 원본 부하를 90% 이상 차단하는 기술.
- **Edge Computing**: CDN 엣지 노드에서 가벼운 함수(CloudFront Functions / Workers)를 실행하여 헤더 조작, 인증, 라우팅을 처리하는 기술.

</details>

- 사용자 물리적 위치와 가장 가까운 PoP로 트래픽을 유도하는 **Anycast 기반 초저지연 라우팅**
- 이미지, JS/CSS, 동영상 등 정적 자산 캐싱을 통한 **원본 서버 트래픽 80% 이상 오프로딩**
- 대규모 트래픽 스파이크 및 악의적 공격을 엣지에서 흡수하는 **DDoS 방어 및 WAF 연계**

#### 한줄 요약
- Anycast 라우팅, 다계층 캐싱, 엣지 보안을 결합하여 글로벌 콘텐츠 전송 품질을 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CDN 3대 계층 구조**: Edge PoP Layer(전 세계 분산 캐시), Origin Shield Layer(중간 집중 캐시), Origin Server Layer(원본 DB/스토리지).

</details>

```text
[CDN 구성]
|-- Anycast DNS
|-- 엣지 노드
|-- 오리진 쉴드
`-- 원본 서버
```

선의 의미: 계층 및 사용자가 엣지 PoP에 접속하여 Cache Hit 시 즉시 응답받고 Miss 시 Shield를 거쳐 원본 서버로 전달되는 다계층 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| Anycast DNS | BGP 기준으로 **최인접 엣지 PoP** 유도 | 초단기 DNS 라우팅 |
| 엣지 노드 | 사용자 근접 **캐시 응답·TLS 종료** 수행 | 전 세계 분산 배치 |
| 오리진 쉴드 | **캐시 미스 요청 병합**으로 원본 보호 | 2차 캐시 계층 |
| 원본 서버 | **정본 콘텐츠·동적 연산** 제공 | S3, Web App |

#### 한줄 요약
- 엣지가 1차 사본을, 오리진 쉴드가 2차 사본과 요청 병합을 맡으므로 원본이 실제로 감당하는 요청 수는 사용자 수가 아니라 캐시 미스 수로 줄어든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **CDN 캐시 요청 처리 5단계**: 엣지 PoP 접속 $\to$ Cache Key 검사 $\to$ Hit 즉시 응답 / Miss Shield 전달 $\to$ 원본 인출 및 TTL 저장 $\to$ 클라이언트 반환.

</details>

```text
클라이언트의 정적 이미지 요청 접수
        │
   1. [엣지 PoP 접속] 브라우저가 Anycast DNS 질의를 통해 가장 지연이 짧은 엣지 서버에 접속
        │
   2. [Cache Key 검사] 요청 URL 및 `Cache-Control` 헤더를 대조하여 로컬 캐시 일치 여부 판별
   ┌────┴───────────────────────────┐
  Cache Hit                         Cache Miss
   │                                 │
3A. [즉시 응답]                     3B. [Origin Shield 전달]
   엣지 메모리에서 10ms 내 응답          Shield를 거쳐 원본 S3에서 데이터 다운로드
   │                                 │
   │                                4. [TTL 캐시 저장]
   │                                   `Cache-Control: max-age=86400` 동안 엣지에 저장
   │                                 │
   └────┬────────────────────────────┘
        ▼
   5. 클라이언트에게 최종 콘텐츠 응답 반환 완료
```

#### 한줄 요약
- Hit는 엣지에서 끝나 원본 왕복이 사라지고 Miss만 원본 비용을 치르므로, TTL을 길게 잡을수록 원본 부하는 줄고 콘텐츠 갱신 반영은 늦어진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Pull vs Push CDN**: 사용자 요청 시 원본에서 긁어오는 방식(Pull)과 배포 시점에 엣지로 미리 밀어넣는 방식(Push).

</details>

| 비교 항목 | 풀 방식 (Pull CDN / Origin Pull) | 푸시 방식 (Push CDN / Origin Push) |
|:---|:---|:---|
| 콘텐츠 적재 시점 | **사용자 요청 시 최초 1회 원본에서 인출 (On-Demand)**| **배포 시점에 전 세계 엣지로 파일 사전 업로드** |
| 첫 사용자 지연 | 최초 요청 시 Cache Miss로 인한 지연 발생 | **첫 사용자부터 100% Cache Hit 초고속 응답** |
| 스토리지 비용 | 사용된 활성 캐시 용량만 점유 (저비용) | 엣지 스토리지 영구 보관으로 상대적 비용 높음 |
| 최적 적용 대상 | **일반 웹 사이트, 이미지, JS/CSS 에셋** | **대용량 게임 패치, OS 설치 이미지, 대작 VOD**|

#### 한줄 요약
- 일반 웹 리소스는 Pull CDN, 대용량 게임 패치 및 VOD는 Push CDN을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Content Hashing**: 소스코드 빌드 시 파일명에 해시값(`app.a8f9b2.js`)을 부여하여 CDN 캐시 무효화(Purge) 비용 없이 무중단 배포하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프론트엔드 배포 후 엣지 캐시로 구버전 화면 표출 | **정적 자산에 Content Hash 빌드명(`app.a8f9b2.js`) 부여** | 무효화(Purge) 비용 0원 및 즉시 최신화 |
| 로그인 사용자 개인정보 페이지가 엣지에 잘못 캐싱되어 유출 | **동적 API 응답에 `Cache-Control: no-store, private` 강제** | 개인정보 캐시 유출 사고 원천 차단 |
| 수백 개 엣지 동시 미스로 인한 원본 다운 (Thundering Herd)| **`Origin Shield` 활성화 및 요청 병합(Request Collapsing) 적용** | 원본 서버 트래픽 95% 이상 방어 |
| 글로벌 배포 시 특정 국가의 접속 차단 규제 | **Geo-Restriction(지리적 위치 차단) 및 엣지 WAF 정책 적용** | 글로벌 규제 준수 및 보안 확보 |

#### 한줄 요약
- 네 대책은 사본을 사용자 가까이 둔 대가인 구버전 노출과 잘못된 캐싱, 동시 미스 위험을 해시 버저닝과 헤더 통제로 되사는 조치다.

## Ⅶ. 결론

- 글로벌 웹 서비스, 대용량 미디어 스트리밍 및 SaaS 애플리케이션의 성능과 가용성을 보장하는 **가장 핵심적인 글로벌 엣지 딜리버리 인프라 표준**으로 확립되었으며, 실무 구축 시에는 **정적 에셋 배포 시 캐시 무효화 비용을 없애는 Content Hash 빌드명(`app.[hash].js`) 적용, 개인정보 유출을 방어하는 `Cache-Control: private, no-store` 엄격 분리, 수백 개 엣지 캐시 미스 폭주를 방어하는 Origin Shield 및 요청 병합(Request Collapsing), CloudFront Functions/Cloudflare Workers를 활용한 엣지 컴퓨팅**을 결합하여 성능 최적화와 보안성을 완벽히 조화

#### 한줄 요약
- CDN은 Anycast 라우팅과 다계층 엣지 분산 캐싱을 통해 원본 서버 부하를 최소화하고 사용자에게 초저지연 콘텐츠를 제공하는 핵심 웹 인프라 기술이다.
