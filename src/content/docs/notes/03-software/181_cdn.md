## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **CDN(Content Delivery Network)**: 사용자 근접 에지 서버(Edge Server)에 정적 자산을 캐싱하여 원본 서버(Origin Server) 부하를 경감하고 지연 시간(Latency)을 최소화하는 분산 네트워크.
- **오리진 서버(Origin Server)**: 원본 데이터가 저장된 서비스의 최종 정본 저장소.
- **에지 노드/PoP(Edge Node/Point of Presence)**: 사용자 물리적 근접 위치에서 콘텐츠를 고속 전송하는 캐시 서버 군집.

</details>

- 정의: 네트워크 거리에 따른 지연 시간(RTT)을 극복하고, 원본 서버의 트래픽 과부하 방지를 위해 콘텐츠를 에지 서버로 분산 배치하는 고가용성 전송 기술.
- 배경: 지리적 RTT 한계 극복, 사용자 체감 품질(QoE) 향상, 서버 부하 분산.

## Ⅱ. 핵심 라우팅 메커니즘

<details><summary>핵심 용어</summary>

- **애니캐스트(Anycast)**: 동일 IP를 다수 서버에 할당하여 BGP 경로 탐색을 통해 최단 지연 시간 노드로 유도하는 라우팅 기술.
- **지리적 라우팅(Geo-Routing)**: 클라이언트 IP의 지리적 위치 정보를 기반으로 물리적 근접 PoP(Point of Presence)를 할당하는 기술.
- **리버스 프록시 캐싱(Reverse Proxy Caching)**: 에지 서버가 클라이언트 요청을 가로채어(Intercept) 캐시 데이터를 응답하고, 부재 시 원본과 동기화하는 기법.
- **DDoS 완화(DDoS Mitigation)**: 에지 노드의 대규모 대역폭을 활용하여 공격 트래픽을 분산·흡수하고 원본 서버를 보호하는 보안 기술.

</details>

- 라우팅과 캐싱 통합으로 최적 경로 할당 및 트래픽 폭주 방지.

## Ⅲ. 다층 계층 아키텍처

<details><summary>핵심 용어</summary>

- **쉴드 캐시(Shield Cache)**: 다수 에지 노드의 캐시 미스(Cache Miss) 요청을 집약하여 원본 부하를 방지하는 중간 계층 캐시.

</details>

```text
┌────────────────────────────────────────────────────────────┐
│                  다층 계층 CDN 아키텍처                    │
├────────────────────────────────────────────────────────────┤
│ 1. [클라이언트] ──(DNS/애니캐스트)─► 2. [에지 지점 (서울)]  │
│                                       │ (미스 시)          │
│ 4. [원본 서버] ◄──(요청)─── 3. [쉴드 캐시 (도쿄)]          │
└────────────────────────────────────────────────────────────┘
```

| 구성요소 | 핵심 역할 | 실무 사례 |
|:---|:---|:---|
| **DNS** | GSLB 기반 최적 에지 IP 반환 | Route53 |
| **Edge PoP** | 엔드유저 대상 최전방 콘텐츠 전송 | CloudFront 에지 |
| **Shield** | 에지 요청 집약 및 원본 보호 | 리저널 캐시 |
| **Origin** | 최종 정본 데이터 저장소 | S3, Nginx |

## Ⅳ. 콘텐츠 요청 파이프라인

<details><summary>핵심 용어</summary>

- **캐시 적중률(Cache Hit Ratio)**: 원본 접근 없이 에지에서 즉시 처리된 요청의 비율.

</details>

```text
[Client]              [Edge Node]        [Origin]
   │                       │                │
   ├─ 1. DNS Query ───────►│                │
   ├─ 2. HTTP GET ───────►│                │
   │                      ├─ 3. 캐시 미스  │
   │                      ├─ 4. 원본 조회 ─►│
   │                      │                │
   │◄─ 5. 캐시 저장 ──────┼─ 6. 응답 ◄─────┤
```

- 흐름: 인접 에지 접속 → 미스 시 쉴드/원본 조회 → 데이터 캐싱 후 응답.

## Ⅴ. 배포 방식 비교

<details><summary>핵심 용어</summary>

- **Push CDN**: 배포 시점에 콘텐츠를 에지로 사전 로딩(Pre-loading)하는 방식.

</details>

| 항목 | Pull CDN (일반 웹) | Push CDN (대용량) |
|:---|:---|:---|
| **동작** | 요청 시 원본에서 인출 | 배포 시점에 에지로 밀어넣음 |
| **데이터** | 일반 웹 리소스 | VOD, 게임 패치 |
| **장점** | 단순 설정, 용량 효율 | 첫 사용자 응답 속도 최적 |

## Ⅵ. 실무 난제 및 대책

<details><summary>핵심 용어</summary>

- **퍼지(Purge/Invalidation)**: 에지 캐시 내 노후 데이터(Stale)를 강제 삭제하는 API 호출.

</details>

| 난제 | 원인 | 대책 |
|:---|:---|:---|
| **갱신 지연** | 긴 TTL(Time To Live) | 강제 퍼지, URL 버저닝 |
| **동적 콘텐츠** | 로그인별 데이터 상이 | Cache-Control: private, 패스(Bypass) |
| **CORS 에러** | 도메인 불일치 | 헤더 설정(`Access-Control-Allow-Origin`) |

- **전략**: 콘텐츠 해시 기반 버저닝 및 긴 TTL 활용 무효화 없는 무한 캐싱.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **에지 컴퓨팅(Edge Computing)**: 엣지 서버 내 로직 실행(AWS Lambda@Edge)으로 동적 데이터 가속.

</details>

- 에지 기반 콘텐츠 가속 및 버저닝 전략 최적화 체계 적용.
