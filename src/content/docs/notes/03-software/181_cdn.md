## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CDN (Content Delivery Network)**: 지리적으로 분산된 엣지 서버(Edge PoP)에 정적 및 동적 웹 콘텐츠를 캐싱하여, 사용자와 물리적으로 가장 가까운 위치에서 초고속으로 전송하는 분산 네트워크 아키텍처.
- **원거리 원본 서버 병목(Origin Latency & Bandwidth Bottleneck)**: 중앙의 단일 원본(Origin) 서버로 전 세계 모든 트래픽이 집중됨에 따라 발생하는 네트워크 왕복 지연(RTT)과 대역폭 과부하 위험.

</details>

- 정의/개념: 전 세계 분산된 엣지 서버(Edge PoP)에 **정적·동적 콘텐츠를 캐싱하여 지연시간을 단축하고 대역폭을 절감**하는 분산 전송 네트워크
- 배경/필요성: 원거리 단일 원본(Origin) 서버로의 직접 트래픽 집중으로 인한 **네트워크 지연(RTT), 대역폭 비용 폭증 및 원본 서버 다운 위험** 직면

#### 한줄 요약

- 전 세계 엣지 PoP를 통한 캐싱 및 애니캐스트(Anycast) 라우팅을 기반으로 사용자 응답 속도를 극대화하고 원본 부하를 절감

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **애니캐스트(Anycast) BGP 라우팅**: 전 세계 수백 개 엣지 서버에 단일 가상 IP를 공유하고 인터넷 라우팅 최단 경로(AS-Path)의 엣지 PoP로 트래픽을 자동 분산 유도.
- **오리진 쉴드(Origin Shield)**: 다수의 엣지 PoP와 원본 서버 사이에 중간 캐시 계층을 두어 캐시 미스(Cache Miss) 시 발생하는 원본 서버 부하를 90% 이상 차단.

</details>

- 사용자 물리적 위치와 가장 가까운 PoP로 트래픽을 전달하는 **Anycast 기반 초저지연 라우팅**
- 이미지, JS/CSS, 동영상 등 정적 자산 캐싱을 통한 **원본 서버 트래픽 80% 이상 오프로딩**
- 대규모 트래픽 스파이크 및 악의적 공격을 엣지에서 흡수하는 **DDoS 방어 및 WAF 연계** #### 한줄 요약

- Anycast 라우팅과 다계층 캐싱을 결합하여 콘텐츠 전송 성능과 글로벌 서비스 가용성을 확보

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CDN 계층 구조**: Anycast DNS, Edge PoP(사용자 접점), Origin Shield(중간 캐시 계층), Origin Server(중앙 원본).

</details>

```text
[ CDN 분산 캐싱 및 다계층 아키텍처 구조도 ]

 [ 글로벌 사용자 (Client) ]
              │ (Anycast DNS ➔ 최단 경로 PoP 접속)
              ▼
 1. [ 엣지 PoP (Edge Point of Presence) ] (전 세계 분산 캐시)
    • Cache Hit  ──► 즉시 정적 파일 응답 (수 ms 이내)
    • Cache Miss ──► Origin Shield로 요청 전달
              │
              ▼
 2. [ 오리진 쉴드 (Origin Shield / Regional Edge Caches) ]
    • 다수 엣지 노드의 캐시 미스 요청 병합 (Request Collapsing)
              │ (Shield Miss 시에만 원본 조회)
              ▼
 3. [ 원본 서버 (Origin Server: AWS S3 / EC2 Web App) ]
```

선의 의미: 사용자가 엣지 PoP에 접속하여 Cache Hit 시 즉시 응답받고, Miss 시 Shield를 거쳐 원본 서버로 전달되는 다계층 구조.

| 구성요소 | 책임 |
|:---|:---|
| Anycast DNS | 클라이언트 요청을 BGP 라우팅 기준으로 **지리적으로 가장 가까운 엣지 PoP로 유도** |
| 엣지 노드 (Edge PoP) | 사용자 근접 위치에서 **정적 자산 캐시 응답 및 SSL/TLS 종료(Termination) 수행** |
| 오리진 쉴드 (Origin Shield) | 여러 엣지 PoP의 **캐시 미스 요청을 하나로 병합(Coalescing)하여 원본 서버 보호** |
| 원본 서버 (Origin Server) | 콘텐츠의 **최종 정본 데이터 저장 및 동적 비즈니스 트랜잭션 연산 수행** |

#### 한줄 요약

- Anycast DNS, 엣지 PoP, 오리진 쉴드, 원본 서버가 결합하여 다계층 분산 캐싱을 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **CDN 캐시 요청 처리 5단계 파이프라인**: 엣지 PoP 접속 $\to$ Cache Key 검사 $\to$ Cache Hit 응답 $\to$ Shield/Origin 인출 $\to$ 엣지 저장 및 반환.

</details>

```text
[ CDN 콘텐츠 요청 및 캐싱 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 사용자의 Anycast 최단 엣지 PoP 접속 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. Cache Key(URL + Header) 일치 검사  │
 ├───────────────────┬────────────────────┤
 │ Cache Hit         │ Cache Miss         │
 │ 3A. 엣지 메모리   │ 3B. Origin Shield  │
 │     즉시 반환     │     원본 요청 전달 │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 원본 응답 수신 및 TTL 기반 캐시 저장│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 클라이언트에게 최종 콘텐츠 응답 반환│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 엣지 접속: 브라우저가 DNS 질의를 통해 가장 지연시간이 짧은 Anycast 엣지 PoP IP로 연결.
2. 캐시 검사: 엣지 서버가 요청 URL 및 `Cache-Control` 헤더를 바탕으로 로컬 캐시 일치 여부를 판별.
3. Hit 반환: 캐시에 유효한 자산이 있으면(Hit) 원본 서버 통신 없이 10ms 이내에 즉시 클라이언트에 응답.
4. 원본 조회: 캐시에 없으면(Miss) Origin Shield를 거쳐 원본 서버(S3)에서 데이터를 다운로드.
5. 캐시 저장: HTTP `Cache-Control: max-age=86400` 헤더에 명시된 TTL 동안 엣지 디스크에 저장하고 사용자에게 반환.

#### 한줄 요약

- 엣지 접속 $\to$ 캐시 검사 $\to$ Hit 즉시 반환 / Miss 원본 조회 $\to$ 엣지 저장 $\to$ 클라이언트 반환의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Pull CDN vs Push CDN**: 사용자 요청 시 원본에서 긁어오는 방식(Pull)과 배포 시점에 엣지로 미리 밀어넣는 방식(Push).

</details>

| 구분 | 풀 방식 (Pull CDN / Origin Pull) | 푸시 방식 (Push CDN / Origin Push) |
|:---|:---|:---|
| **적용 기준** | 일반 웹 사이트, 이미지, JS/CSS, 빈번히 갱신되는 웹 자산 | 대용량 게임 패치 파일, 대작 VOD 동영상, 소프트웨어 설치 파일 |
| **핵심 특징** | **사용자 요청 시 최초 1회 원본에서 인출 후 캐싱 (On-Demand)** | **배포 즉시 전 세계 엣지 스토리지로 파일을 사전 복제 업로드** |
| **한계** | 첫 번째 사용자는 Cache Miss로 인한 초기 지연 발생 | 엣지 스토리지 점유 비용 발생 및 사전 전송 시간 소요 |

#### 한줄 요약

- 일반 웹 리소스는 Pull CDN, 대용량 게임 패치 및 VOD는 Push CDN을 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 무효화(Purge / Invalidation)**: 소스코드 배포 시 엣지 서버에 남아있는 구버전 JS/CSS 파일을 강제로 삭제하는 API 작업.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프론트엔드 배포 후 엣지 캐시로 인해 구버전 화면 표출 | **정적 자산에 Content Hash 빌드명(`app.a8f9b2.js`) 부여** | 무효화(Purge) 비용 0원 및 즉시 최신화 |
| 로그인 사용자 개인정보 페이지가 엣지에 잘못 캐싱되어 유출 | **동적 API 응답에 `Cache-Control: no-store, private` 강제** | 개인정보 캐시 유출 사고 원천 차단 |
| 수백 개 엣지에서 동시에 원본으로 몰려 Origin 다운(Thundering Herd) | **`Origin Shield` 활성화 및 요청 병합(Request Collapsing) 적용** | 원본 서버 트래픽 95% 이상 방어 |

#### 한줄 요약

- 파일 해시 버저닝, Private 헤더 통제, Origin Shield 요청 병합을 통해 CDN 운영 결함을 방어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **엣지 컴퓨팅(Edge Computing / CloudFront Functions)**: CDN 엣지에서 경량 자바스크립트를 실행하여 URL 리라이팅, 헤더 조작, A/B 테스트를 초저지연으로 수행하는 진화 기술.

</details>

- **CDN 콘텐츠 전송 네트워크** 기반 글로벌 대고객 서비스의 성능과 가용성을 보장하는 필수 인프라 계층이며, 해시 기반의 불변 캐싱 전략과 Origin Shield를 결합하여 비용 절감과 초저지연 사용자 경험을 완성해야 함

#### 한줄 요약

- Anycast 라우팅과 다계층 엣지 캐싱을 통해 원본 서버를 보호하고 초고속 글로벌 콘텐츠 전송을 완성
