## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **골든 패스 및 IDP(Golden Path & IDP)**: 개발자가 인프라 상세 지식 없이도 검증된 표준 템플릿(Golden Path)을 통해 단일 포털(Backstage)에서 환경을 자동 생성하는 셀프서비스 플랫폼.
- **개발자 인지 부하 및 인프라 병목(Cognitive Load & Bottleneck)**: K8s YAML, 클라우드 IAM 등 과도한 인프라 설정 학습 부담으로 본연의 비즈니스 로직 개발 생산성이 저하되는 한계.

</details>

- 정의/개념: 개발자의 인지 부하(Cognitive Load)를 경감하고 개발 생산성을 높이기 위해 **골든 패스(Golden Path) 및 셀프서비스 포털(IDP)** 을 제공하는 엔지니어링 패러다임
- 배경/필요성: DevOps 확산에 따른 개발자의 클라우드·인프라 도구 학습 부담 폭증 및 **인프라 티켓 처리 병목과 보안 설정 오류 위험** 직면

#### 한줄 요약

- 내부 개발자 플랫폼(IDP)과 골든 패스를 통해 인프라 복잡성을 추상화하고 개발자 셀프서비스를 구현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **셀프서비스 기능(Self-Service)**: 인프라팀에 티켓 요청 없이 개발자가 포털에서 클릭이나 선언적 파일로 K8s 네임스페이스와 DB를 즉시 프로비저닝하는 역량.
- **가드레일 정책(Policy as Code)**: Open Policy Agent(OPA) 등을 통해 보안, 비용, 규정 준수 기준을 코드로 강제하여 자율성과 안정성을 동시 확보하는 기법.

</details>

- 개발자의 복잡한 인프라 학습 부담을 덜어주는 **인지 부하(Cognitive Load) 최소화**
- 검증된 모범 사례를 템플릿화한 **골든 패스(Golden Path) 기반 셀프서비스 제공**
- 플랫폼을 내부 고객을 위한 제품으로 취급하는 **Platform as a Product 사상 정립**

#### 한줄 요약

- 인지 부하 경감, 셀프서비스 포털, 정책 가드레일을 통해 개발자 경험(DX)과 조직 생산성을 극대화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Backstage**: CNCF 오픈소스 내부 개발자 포털로 서비스 카탈로그, 템플릿(Software Templates), 기술 문서(TechDocs)를 단일 웹 콘솔로 통합.

</details>

```text
[ 플랫폼 엔지니어링 5계층 아키텍처 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │ 1. Developer Control Plane (개발자 단일 포털: Backstage UI / CLI)       │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 2. Integration Plane (IDP 코어 오케스트레이터: Score / Humanitec)      │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 3. Security & Policy Plane (Policy-as-Code: Open Policy Agent - OPA)   │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 4. Resource Plane (인프라 자동화 엔진: Terraform, Crossplane, Helm)     │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 5. Infrastructure Plane (K8s 클러스터, AWS, GCP, DB, 메시지 브로커)    │
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 포털에서 셀프서비스 요청 시 오케스트레이터가 정책을 검증하고 클라우드 인프라를 자동 생성하는 5단계 계층.

| 구성요소 | 책임 |
|:---|:---|
| 개발자 포털 (Backstage) | 서비스 카탈로그, 표준 템플릿, 문서(TechDocs)를 제공하는 **단일 웹 진입점** |
| 플랫폼 오케스트레이터 | 개발자 선언 파일(Score)을 해석하여 **환경별 리소스 매핑 및 워크플로 실행** |
| 정책 가드레일 (OPA) | 규정 준수, 비용 한도, 보안 규칙을 **코드로 자동 검증하여 배포 승인** |
| 리소스 프로비저너 | Terraform 및 Crossplane을 통해 **클라우드 인프라를 동적 프로비저닝** |

#### 한줄 요약

- 단일 포털 진입점부터 정책 검증 및 인프라 프로비저닝까지 5개 계층으로 연결된 자동화 체계

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Score Spec**: 개발자가 인프라 상세 지식 없이 필요한 리소스(DB, Cache)를 선언하면 환경에 맞는 코드로 변환해 주는 워크로드 명세 표준.

</details>

```text
[ IDP 셀프서비스 개발 환경 생성 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 포털 접속: Backstage 로그인         │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 템플릿 선택: 골든 패스(Spring/Node) │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 정책 검증: OPA 기반 보안·비용 검사 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 자동 프로비저닝: K8s/DB 1분 내 생성 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 포털 접속: 개발자가 단일 개발자 포털(Backstage)에 접속하여 서비스 카탈로그를 확인.
2. 템플릿 선택: 원하는 기술 스택의 골든 패스(Software Template)를 선택하고 프로젝트 메타데이터 입력.
3. 정책 검증: Policy-as-Code(OPA) 엔진이 리소스 한도, 보안 정책, 태그 규칙 부합 여부를 자동 심사.
4. 자동 프로비저닝: CI/CD 파이프라인 및 Crossplane이 K8s 네임스페이스와 클라우드 DB를 즉각 생성하여 개발 환경을 배포.

#### 한줄 요약

- 포털 접속 $\to$ 골든 패스 선택 $\to$ 정책 검증 $\to$ 인프라 자동 생성의 4단계 셀프서비스 절차

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DevOps vs SRE vs Platform Engineering**: 개발/운영 결합 문화(DevOps), 시스템 신뢰성 엔지니어링(SRE), 개발자 인지 부하 감소를 위한 내부 플랫폼 제품화(Platform Engineering).

</details>

| 구분 | Traditional DevOps | SRE (Site Reliability Eng.) | Platform Engineering |
|:---|:---|:---|:---|
| **적용 기준** | 개발팀 중심의 자율 배포 및 운영 | 대규모 분산 시스템의 신뢰성 보증 | 다수 개발팀의 인지 부하 경감 및 표준화 |
| **핵심 특징** | **"You Build It, You Run It" 문화** | **SLO/SLA 기반 에러 예산 및 장애 통제** | **IDP 및 골든 패스 기반 셀프서비스 제품화** |
| **한계** | 개발자의 인프라 도구 피로도 급증 | 인프라 생성 및 배포 병목 해소 한계 | 초기 플랫폼 구축 투자 및 전담팀 공수 필요 |

#### 한줄 요약

- DevOps는 문화 결합, SRE는 운영 신뢰성, 플랫폼 엔지니어링은 인지 부하 경감과 셀프서비스에 집중

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Escape Hatch(탈출구)**: 플랫폼의 표준 골든 패스로 해결되지 않는 특수 요구사항에 대해 개발자가 하부 인프라를 직접 제어할 수 있도록 열어두는 예외 통로.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 개발자들이 IDP를 외면하고 기존 인프라팀에 수동 문의 | **압도적으로 편리한 골든 패스 제공 및 개발자 피드백 중심 제품 개선** | 플랫폼 채택률 및 개발자 만족도(DX) 극대화 |
| 플랫폼의 과도한 추상화로 정밀 인프라 튜닝 불가 | **특수 요구사항을 위한 예외 통로(Escape Hatch) 공식 마련** | 개발 유연성과 표준 가드레일의 공존 |
| IDP 구축을 위한 초기 공수 및 비용 부담 | **오픈소스 Backstage 및 경량 도구(Score) 기반 MVP 점진 구축** | 초기 투자 리스크 최소화 및 신속한 가치 검증 |

#### 한줄 요약

- 편리한 골든 패스, Escape Hatch 예외 허용, 점진적 MVP 도입으로 성공적인 플랫폼 전환을 달성

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **개발자 경험(DX, Developer Experience)**: 개발자가 소프트웨어를 기획, 작성, 배포하는 전 과정에서 느끼는 효율성과 만족도 지표.

</details>

- **플랫폼 엔지니어링**은 복잡한 클라우드 네이티브 환경에서 개발자가 본연의 비즈니스 가치 창출에 전념할 수 있도록 돕는 핵심 전략이며, 지속적인 내부 피드백을 통해 진화하는 플랫폼을 구축해야 함

#### 한줄 요약

- IDP와 골든 패스를 통해 인프라를 제품화하고 개발자 셀프서비스를 실현하여 전사 생산성을 혁신
