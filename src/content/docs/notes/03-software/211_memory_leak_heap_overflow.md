## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **메모리 누수(Memory Leak)**: 더 이상 필요하지 않은 객체가 참조에 남아 회수되지 않고 점유량이 계속 누적되는 결함이다.
- **힙 고갈(Heap Exhaustion)**: 가용 힙이 부족해 새 객체의 메모리 할당이 실패하는 상태이다.

</details>

- 정의/개념: **메모리 누수(Memory Leak)**는 불필요한 객체가 회수되지 않는 결함이고 **힙 고갈(Heap Exhaustion)**은 가용 힙 부족으로 새 할당이 실패하는 상태이다.
- 배경/필요성: OOM만으로는 누수•정상 고점유•용량 부족을 구분하기 어렵다.

#### 한줄 요약

- 불필요한 객체의 참조를 해제하지 않으면 힙이 점유되고, 결국 새 할당이 불가능해져 프로그램이 실패한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **힙 덤프•도미네이터 경로**: 객체와 참조 관계를 기록하고 증가 객체를 붙잡는 핵심 참조 원인을 찾는 진단 수단이다.
- **가비지 컬렉션(Garbage Collection, GC)**: 더 이상 도달할 수 없는 객체의 메모리를 자동 회수하는 작업이다.
- **메모리 부족(Out Of Memory, OOM)**: 프로그램이 필요한 메모리를 더 할당하지 못해 오류가 발생하는 상태이다.
- **스레드 로컬(ThreadLocal)**: 스레드마다 독립된 값을 보관하며 정리하지 않으면 장수 스레드가 객체를 계속 참조할 수 있는 저장 영역이다.
- **네이티브 메모리(Native Memory)**: 관리형 힙 밖에서 운영체제나 외부 라이브러리가 직접 할당하는 메모리이다.

</details>

- 누수는 **가비지 컬렉션(Garbage Collection, GC)** 후 기준 점유량이 지속 상승한다.
- 고갈은 누수•큰 작업 집합•과도한 동시 할당으로 발생한다.
- **힙 덤프•도미네이터 경로**로 잔존 참조 원인을 추적한다.
- 리스너•**스레드 로컬(ThreadLocal)** 해제 누락은 힙 참조를 남긴다.
- **네이티브 메모리(Native Memory)** 해제 누락은 힙 외부 누수를 일으킨다.

#### 한줄 요약

- 부하가 줄었는데도 힙 사용량 기저선이 계속 상승하면 누수를 의심하고, 단발성 피크로 초과했다면 힙 크기•상한 설정도 함께 점검한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **참조•점유 분석기(Reference and Retention Analyzer)**: 시점별 객체 수•보유 크기•도미네이터를 비교해 누수 후보를 판정하는 구성요소이다.
- **보유 크기(Retained Size)**: 특정 객체가 회수될 때 함께 회수될 수 있는 객체 그래프의 전체 메모리 크기이다.
- **도미네이터(Dominator)**: 특정 객체로 향하는 모든 참조 경로가 반드시 통과해 하위 객체의 생존을 지배하는 객체이다.
- **메모리 계측기(Memory Instrumentation)**: 힙•네이티브•GC•할당 추이를 지속 수집하는 구성요소이다.
- **덤프•프로필 수집기(Dump and Profile Collector)**: 시점별 객체•참조•할당 자료를 보존하는 구성요소이다.
- **운영 제어기(Operational Controller)**: 분석 결과에 따라 참조 수명과 캐시•큐•힙 상한을 조정하는 구성요소이다.

</details>

```text
          [메모리 계측기]
                 |
       [덤프•프로필 수집기]
                 |
        [참조•점유 분석기]
                 |
           [운영 제어기]
```

선의 의미: 메모리 계측과 덤프•프로필 자료가 참조•점유 분석 계층을 뒷받침하고, 분석 결과가 운영 제어 기준과 결합되는 정적 진단 도구 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| **메모리 계측기(Memory Instrumentation)** | 힙•네이티브•GC•할당 추이 수집 |
| **덤프•프로필 수집기(Dump and Profile Collector)** | 시점별 객체•참조•할당 기록 |
| **참조•점유 분석기(Reference and Retention Analyzer)** | **보유 크기(Retained Size)**•**도미네이터(Dominator)** 판정 |
| **운영 제어기(Operational Controller)** | 참조 수명과 캐시•큐•힙 상한 조정 |


#### 한줄 요약

- 힙 사용량 추이 그래프와 객체 참조 그래프를 함께 분석하여 누수 원인 객체를 식별하는지, 힙 크기 자체가 부족한지를 구분한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 반복 부하•GC 후 덤프**: 같은 부하를 반복하고 GC 뒤의 기준 점유량과 힙 덤프를 기록하는 단계이다.
- **2. 객체•참조 차이 전달**: 시점별 객체 수와 보유 크기의 증가분을 비교하는 단계이다.
- **3. 증가 객체•보유 경로 판정**: 증가한 객체를 붙잡는 도미네이터와 잔존 참조를 추적하는 단계이다.
- **4. 누수•정상 고점유•고갈 분류**: 회복 여부•보유 크기•할당 실패로 상태를 구분하는 단계이다.
- **5. 검증 부하 계측**: 수정 후 같은 부하에서 기준선•GC•OOM 발생 여부를 다시 확인하는 단계이다.

</details>

```text
1. 반복 부하•GC 후 덤프
      |
      v
2. 객체•참조 차이 전달
      |
      v
3. 증가 객체•보유 경로 판정
      |
      v
4. 누수•정상 고점유•고갈 분류
      |
      +-- GC 후 기준선 회복 --> 정상 고점유•용량 검토
      |
      +-- 보유 크기 지속 상승 --> 메모리 누수•참조 해제
      |
      +-- 새 할당 실패 --> 힙 고갈•누수•작업량 원인 분리
                              |
                              v
5. 검증 부하 계측
```

### 동작 원리

1. **반복 부하•GC 후 덤프**: 부하 전후 기준 점유량을 기록한다.
2. **객체•참조 차이 전달**: 시점별 객체 수•보유 크기를 비교한다.
3. **증가 객체•보유 경로 판정**: 도미네이터의 잔존 참조를 추적한다.
4. **누수•정상 고점유•고갈 분류**: 회복 여부•원인 영역으로 구분한다.
5. **검증 부하 계측**: 수정 후 기준선•GC•OOM을 재확인한다.


#### 한줄 요약

- 같은 일을 반복하고 청소한 뒤에도 남는 물건이 늘면 연결 지도를 따라 붙잡은 주인을 찾아 고친다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **메모리 누수 판정 기준**: GC 뒤에도 불필요한 객체와 보유 크기가 계속 증가하는지 확인하는 기준이다.
- **정상 고점유(Healthy High Utilization)**: 작업 중 메모리 사용량이 높아져도 부하 종료와 GC 뒤 기준선으로 회복되는 상태이다.
- **힙 고갈 판정 기준**: 가용 힙 부족으로 새 객체 할당이 실패했는지 확인하는 기준이다.

</details>

| 메모리 상태 | 판별 신호 | 의미 |
|:---|:---|:---|
| **정상 고점유(Healthy High Utilization)** | 부하 종료와 GC 뒤 기준선 회복 | 작업 집합에 따른 일시적 점유 상승 |
| **메모리 누수 판정 기준** | GC 뒤에도 객체•보유 크기 지속 증가 | 불필요한 참조가 남아 기준선 상승 |
| **힙 고갈 판정 기준** | 가용 힙 부족으로 새 할당 실패 | 누수•큰 작업 집합•동시 할당의 결과 상태 |

> 요약: GC 후 회복은 정상, 누적은 누수, 할당 실패는 고갈이 핵심이다.

#### 한줄 요약

- 일이 끝나 비워지면 정상이고 바닥선이 계속 오르면 누수이며 새 물건을 못 놓는 순간은 고갈이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **누수 오판**: 높은 할당률과 일시적 GC 증가를 잔존 객체의 지속 증가로 잘못 해석하는 문제이다.
- **힙 덤프 분석**: 시점별 힙 객체•값•참조 관계를 비교하는 진단이다.
- **할당률(Allocation Rate)**: 단위 시간에 새로 생성되어 힙에 할당되는 메모리 양이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| GC 증가의 **누수 오판** | **할당률(Allocation Rate)**•잔존 객체 동시 분석 | 원인 진단 정확성 |
| **힙 덤프 분석** 자료의 민감정보 노출 | 암호화•마스킹•접근 통제 | 자료 유출 방지 |
| 재시작의 원인 은폐 | 덤프•지표 확보 후 제한 재시작 | 근본 원인 추적성 |
| 고갈 직전의 늦은 경보 | 추세•증가율•예측 임계치 | 장애 사전 완화 |

#### 한줄 요약

- 화면이 닫혀도 남은 이벤트 연결이 객체를 붙잡는다면 해제 시점에 그 연결을 끊는다.



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **메모리 대응 기준**: GC 후 기준선이 지속 상승하면 불필요한 참조를 해제하고 일시 고점유이면 작업량과 용량 상한을 조정하는 기준이다.
- **기준선 회복(Baseline Recovery)**: 부하 종료와 GC 뒤 메모리 점유량이 안정된 이전 수준으로 돌아오는 현상이다.

</details>

- **메모리 대응 기준**에 따라 **기준선 회복(Baseline Recovery)** 여부를 확인하고 누수이면 참조를 해제하며 일시 고점유이면 용량 상한을 조정한다.

#### 한줄 요약

- 힙부터 늘리지 말고 청소 뒤에도 남는 참조가 누적인지, 정상 작업량이 용량을 넘는지 먼저 구분한다.
