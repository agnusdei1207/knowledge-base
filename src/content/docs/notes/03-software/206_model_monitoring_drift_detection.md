## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **모델 모니터링(Model Monitoring)**: 운영 환경에서 발생하는 입력 데이터, 모델의 예측값, 실제 정답(Label)을 학습 시점의 기준선과 비교 분석하여, 모델의 품질 저하 및 이상 변화를 지속적으로 관찰하고 대응하는 일련의 활동 체계이다.
- **드리프트(Drift)**: 현실 세계의 트렌드 변화나 사용자 행동 패턴의 변경으로 인해, 운영 데이터의 분포(Data Drift)나 입력과 정답 간의 상관관계(Concept Drift)가 초기 학습 시점과 달라져 모델 성능을 떨어뜨리는 현상이다.

</details>

- 정의/개념: 운영 환경의 실시간 신호를 수집하여 **드리프트(Drift)** 발생 여부와 이로 인한 모델 품질 저하를 조기에 판정하고 조치하는 **모델 모니터링(Model Monitoring)** 체계이다.
- 배경/필요성: 배포 전 단계의 정적 평가만으로는 배포 이후 발생하는 운영 데이터의 분포 변화나 현실 세계의 개념 변화를 선제적으로 반영하고 대응하기 어렵기 때문에 도입이 필수적이다.

#### 한줄 요약
- 학습 데이터와 운영 데이터 간의 입력·예측·정답 차이를 비교 분석하여 모델의 노후화 및 성능 저하를 식별하는 모니터링 체계

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **통계 거리(Statistical Distance)•슬라이스 감시(Slice Monitoring)**: KL Divergence, KS Test 등의 통계적 거리 지표를 활용해 운영 데이터 분포의 변화 크기를 정량적으로 측정하고, 전체 데이터가 아닌 특정 사용자군이나 지역별(Slice) 국소적 품질 저하를 세밀하게 찾아내는 감시 기법이다.
- **기준선(Baseline)**: 운영 환경에서의 데이터 변화와 품질 저하 여부를 판정할 때 비교 기준으로 삼기 위해, 모델 학습 및 검증 시점에 확보해 둔 이상적인 데이터 분포와 성능 지표이다.
- **지연 정답(Delayed Label)**: 예측이 이루어진 시점 직후가 아니라 일정 시간이 지난 뒤에야 확정되는 실제 결과값으로, 이를 과거의 예측 결과와 다시 조인(Join)하여 모델의 실질적인 성능을 사후 검증하는 데 사용된다.

</details>

![기준 분포와 운영 분포 사이 거리의 드리프트 경보](/study/diagrams/model-drift-distance.svg)

> 파란 관측 거리가 붉은 경보 임계값을 넘는 시점부터 원인 조사와 재학습을 검토하는 예시이며, 거리 척도와 임계값은 데이터의 특성 및 도메인 위험 수준별로 사전에 검증하여 설정한다.

- **기준선(Baseline)**을 명확히 설정하여 입력 데이터, 모델 예측값, 실제 성능 등 변화를 감지할 대상을 구조적으로 구분한다.
- **통계 거리(Statistical Distance)•슬라이스 감시(Slice Monitoring)** 기법을 통해 전체 및 특정 사용자군별 성능 저하를 조기에 발견하고 경보를 발생시키는 것이 핵심이다.
- **지연 정답(Delayed Label)**이 수집된 후 이를 기존 예측값과 결합하여 정확한 성능 저하 여부를 확인하고, 최종적인 모델 재학습 및 롤백 여부를 결정한다.

#### 한줄 요약
- 실제 정답이 늦게 수집되는 환경에서도 입력 및 예측 데이터의 통계적 변화를 조기 감지하고, 정답 확보 시 실제 정확도 저하 여부를 확정하는 선제적 품질 관리 구조

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **드리프트 탐지기(Drift Detector)**: 기준선과 실시간 운영 데이터 간의 통계적 거리 및 성능 차이를 주기적으로 연산하여, 변화의 유형(Data/Concept)을 분류하고 사전에 설정된 임계치 초과 여부를 자동 판정하는 핵심 엔진이다.
- **기준선 저장소(Baseline Store)**: 모델이 최상의 성능을 냈던 학습 및 검증 시점의 입력 데이터 분포, 예측값, 성능 평가 지표를 불변의 비교 기준으로 안전하게 보관하는 원장 저장소이다.
- **운영 신호 수집기(Operational Signal Collector)**: 시스템 로그, 사용자 입력, 모델의 예측값, 지연 정답 등의 실시간 서비스 지표를 수집하고, 이를 의미 있는 슬라이스(시간, 사용자군 등) 단위로 전처리하여 제공하는 파이프라인 구성요소이다.
- **정답 결합기(Label Joiner)**: 비동기적으로 늦게 도착하는 실제 정답 데이터를 고유 식별자(ID)를 기반으로 과거의 예측 로그와 매핑하여, 운영 환경에서의 실제 모델 성능을 계산할 수 있게 돕는 데이터 처리기이다.
- **대응 제어기(Response Controller)**: 드리프트 탐지기의 분석 결과를 바탕으로 비즈니스 영향도를 평가하여, 모델 재학습(Retraining), 이전 버전으로의 복귀(Rollback), 혹은 단순한 기준선 갱신(Baseline Update) 등의 후속 조치를 최종 결정하고 오케스트레이션하는 제어 모듈이다.

</details>

```text
모델 모니터링 구조
      |
      +-- 비교 자료
      |         +-- [기준선 저장소]
      |         +-- [운영 신호 수집기]
      |         +-- [정답 결합기]
      |
      +-- 판정•대응
                +-- [드리프트 탐지기]
                +-- [대응 제어기]
```

| 구성요소 | 책임 |
|:---|:---|
| **기준선 저장소(Baseline Store)** | 검증된 학습 데이터의 입력, 예측, 성능 분포 지표의 안전한 보관 및 제공 |
| **운영 신호 수집기(Operational Signal Collector)** | 운영 환경의 실시간 입출력 신호를 슬라이스 단위로 분할하여 안정적으로 수집 |
| **정답 결합기(Label Joiner)** | 비동기적으로 도착하는 지연 정답을 과거의 모델 예측 로그와 매핑하여 실성능 기반 마련 |
| **드리프트 탐지기(Drift Detector)** | 운영 데이터와 기준선 간의 통계적 거리 계산 및 성능 임계치 초과 여부 자동 판정 |
| **대응 제어기(Response Controller)** | 탐지 결과에 따른 비즈니스 영향을 평가하고 재학습, 롤백, 기준선 갱신 등의 자동/수동 대응 조치 실행 |

#### 한줄 요약
- 학습 시점의 기준 지표와 운영 신호를 실시간 비교하고, 지연 정답을 결합해 실성능 기반의 자율적 모델 대응을 수행하는 모니터링 아키텍처

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 입력•예측 변화 전달(Input•Prediction Change Delivery)**: 운영 환경에서 발생하는 실시간 입출력 신호를 사용자군, 지역, 시간대 등 다양한 슬라이스 기준으로 분류 및 집계하여 탐지기로 전달하는 데이터 전처리 단계이다.
- **2. 기준선•통계 거리 비교(Baseline•Statistical Distance Comparison)**: 사전 보관된 기준 분포와 전달받은 운영 데이터 분포 간의 차이를 연산하고, 해당 차이가 임계치를 초과하여 지속되는 시간을 정량적으로 측정하는 분석 단계이다.
- **3. 정답•예측 결합(Label•Prediction Join)**: 뒤늦게 확정된 실제 비즈니스 결과(정답)를 과거의 모델 예측 기록과 병합하여, 데이터 분포 변화가 아닌 실제 모델 성능(정확도, F1 Score 등)을 도출하는 평가 단계이다.
- **4. 변화 유형•업무 영향 판정(Change Type•Business Impact Assessment)**: 발생한 드리프트가 단순한 데이터 입력 분포의 변화인지, 핵심 개념의 변화인지 분류하고 이로 인한 서비스 품질 저하 및 비즈니스 피해 규모를 산정하는 진단 단계이다.
- **5. 대응 결정(Response Decision)**: 판정된 변화 원인과 비즈니스 영향을 종합적으로 검토하여, 파이프라인을 통한 즉각적인 모델 재학습, 안전한 구버전으로의 롤백, 혹은 정상적인 변화로 간주한 기준선 갱신 중 최적 조치를 실행하는 제어 단계이다.

</details>

```text
1. 입력•예측 변화 전달
      |
      v
2. 기준선•통계 거리 비교
      |
      +-- 임계 이내 --> 지속 감시 유지
      |
      +-- 임계 초과
              |
              v
3. 정답•예측 결합
      |
      v
4. 변화 유형•업무 영향 판정
      |
      v
5. 대응 결정
      |
      +-- 실제 성능 저하 --> 재학습•복귀 실행
      +-- 영향 없는 변화 --> 기준선 갱신 처리
      +-- 정답 부족 상태 --> 대리지표 감시 전환 및 판정 보류
```

### 동작 원리

1. **입력•예측 변화 전달(Input•Prediction Change Delivery)**: 슬라이스별 운영 데이터 분포를 파이프라인을 통해 주기적으로 수집 및 정제한다.
2. **기준선•통계 거리 비교(Baseline•Statistical Distance Comparison)**: 통계적 분석을 통해 데이터 분포 변화의 규모를 측정하고 임계치 초과 여부를 1차로 판정한다.
3. **정답•예측 결합(Label•Prediction Join)**: 획득한 지연 정답을 예측값과 조인하여 실제 비즈니스 지표 기반의 성능을 정밀 산출한다.
4. **변화 유형•업무 영향 판정(Change Type•Business Impact Assessment)**: 탐지된 이상 현상의 원인을 데이터, 개념, 예측 드리프트로 세분화하고 서비스 피해 정도를 가늠한다.
5. **대응 결정(Response Decision)**: 도출된 진단 결과를 토대로 파이프라인 재가동(재학습), 서비스 안정성 확보(롤백), 혹은 단순 기준 지표 상향(기준선 갱신)을 최종 선택한다.

#### 한줄 요약
- 데이터 분포의 표면적 변화와 정답 관계의 실질적 변화를 단계적으로 교차 검증하여 불필요한 재학습 비용을 방지하는 체계적 대응 프로세스

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 드리프트(Data Drift)**: 모델에 입력되는 운영 데이터의 피처 분포가 환경 변화 등의 이유로 학습 시점의 통계적 분포와 크게 달라져 예측 불안정을 유발하는 현상이다.
- **개념 드리프트(Concept Drift)**: 사용자의 선호도 변화나 외부 경제 상황 변동 등으로 인해 모델의 입력 데이터와 실제 정답 간의 본질적인 상관관계 공식 자체가 뒤바뀌어 치명적인 성능 저하를 초래하는 현상이다.
- **예측 드리프트(Prediction Drift)**: 모델이 최종적으로 출력하는 점수, 등급, 확률 등의 결과값 분포가 과거 기준선 대비 한쪽으로 편향되거나 비정상적으로 변경되는 현상으로, 성능 저하의 선행 지표로 활용된다.

</details>

| 모델 드리프트 유형 | **데이터 드리프트(Data Drift)** | **개념 드리프트(Concept Drift)** | **예측 드리프트(Prediction Drift)** |
|:---|:---|:---|:---|
| 적용 기준 | 정답 확보 이전의 입력 데이터 분포 변화 감시 | 지연 정답 획득 후의 실질적 성능 저하 여부 확인 | 모델의 최종 출력(점수/등급) 쏠림 현상 조기 감시 |
| 핵심 특징 | 운영 환경에서의 피처(Feature) 입력 분포 변동 | 현실 세계의 룰(Rule) 변화에 따른 입력-정답 관계 붕괴 | 모델 예측 결과값 분포의 통계적 편향성 발생 |
| 한계 | 모델 성능에 영향이 없는 변화에도 과잉 경보(False Alarm) 발생 가능 | 정답 수집 지연 시 선제적 판정 및 조치가 지체됨 | 데이터 입력 문제인지 정책 변경에 의한 결과인지 원인 파악 혼동 |

> 요약: 시스템의 변화 대상을 입력 데이터(Data), 입력-정답 관계(Concept), 출력 결과(Prediction)로 명확히 구분하여 맞춤형 감시 체계를 수립한다.

#### 한줄 요약
- 원인 데이터가 달라진 것인지, 현실의 정답 규칙이 변한 것인지, 단순히 결과값만 치우친 것인지를 구분하여 정밀한 타겟 대응 모델 구축

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **드리프트 오판(Drift Misjudgment)**: 명절, 계절 등 정상적이고 주기적인 비즈니스 트렌드 변화를 모델 이상(Drift)으로 잘못 해석하여 불필요한 경보와 무의미한 모델 재학습 파이프라인을 가동시키는 운영 상의 문제점이다.
- **대리지표(Proxy Metric)**: 사용자 클릭률, 체류 시간 등 실제 핵심 정답(예: 최종 구매 확정)이 시스템에 늦게 반영될 때, 모델 성능의 하락 추세를 즉각적으로 추정하고 조기 경보를 울리기 위해 활용되는 간접적인 실시간 지표이다.
- **슬라이스 분석(Slice Analysis)**: 전체 데이터 평균에 가려져 파악하기 힘든 특정 연령대, 소수 인종, 엣지 케이스 지역 등 세부 사용자 그룹 단위의 성능 저하를 개별적으로 분리하여 진단하는 세밀한 분석 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 계절성 요인에 의한 **드리프트 오판(Drift Misjudgment)** | 분석 구간 및 요일 등 비즈니스 주기를 반영한 **기준선(Baseline)** 세분화 및 분리 적용 | 정상적 트렌드 변화와 실제 이상을 구분하여 경보 정확성 향상 |
| 지연 정답으로 인한 성능 저하 탐지 지체 | 실시간 **대리지표(Proxy Metric)** 모니터링 체계와 **지연 정답(Delayed Label)** 비동기 결합 파이프라인 병행 | 정답 지연 환경에서도 모델 성능 하락을 즉각적으로 조기 탐지 및 대응 |
| 다수 지표에서의 동시다발적 경보 폭주 현상 | 비즈니스 임팩트 가중치 부여 및 이상 현상의 지속 시간 상관 분석 기법 도입 | 치명적 결함부터 우선적으로 대응할 수 있는 시스템 가용성 확보 |
| 데이터 입력 변화와 실제 개념 변화 간 원인 혼동 | **슬라이스 분석(Slice Analysis)** 적용 및 입력·예측·정답 파이프라인 분리 진단 체계 구축 | 모델 재학습 여부에 대한 의사결정 정확도 향상 및 리소스 낭비 방지 |

#### 한줄 요약
- 전체 평균 수치의 함정에 빠지지 않도록 세부 고객군 및 비즈니스 주기별 국소 지표를 분리 감시하는 실무적 운영 체계 확보

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **드리프트 대응 기준(Drift Response Criteria)**: 데이터 분포의 단순 변화뿐만 아니라 지연 정답의 병합을 통해 실제 모델 성능 저하가 명확히 입증된 경우에만 비용이 수반되는 재학습을 수행하고, 성능 영향이 없는 트렌드 변화는 기준선 갱신으로 유연하게 수용하는 표준 대응 원칙이다.

</details>

- **드리프트 대응 기준(Drift Response Criteria)**에 입각하여, 정답 결합을 통한 실제 성능 저하 발생 시 즉각적인 재학습을 수행하고 무영향 분포 변화 시 검증 프로세스를 거쳐 기준선을 갱신하는 안정적 운영을 수행해야 한다.

#### 한줄 요약
- 단순 데이터 분포 변화에 의존한 무분별한 재학습을 지양하고, 실제 성능 저하 원인 규명 기반의 유연한 모델 대응 체계 구현 필수
