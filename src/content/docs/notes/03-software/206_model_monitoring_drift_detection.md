## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Model Monitoring & Drift Detection**: 운영 환경의 입력 피처, 예측값, 지연 정답을 학습 기준선(Baseline)과 통계적으로 비교하여 모델 성능 저하를 감시하는 체계.
- **Data Drift vs Concept Drift**: 입력 피처의 통계 분포 변화($P(X)$)와 입력-정답 간의 관계 변화($P(Y|X)$).

</details>

- 정의/개념: 운영 환경의 입력 데이터, 예측값, 지연 정답을 기준선과 대조하여 **데이터 및 개념 드리프트를 실시간 감시하는 MLOps 품질 관리 체계**
- 배경/필요성: 사용자 행동 및 경제 환경 변화로 인한 **데이터 분포 변화(Drift), 모델 성능 급락 및 비즈니스 예측 실패 해결 불가**

#### 한줄 요약
- 통계적 가설 검정(KS-Test, PSI)과 지연 정답 결합을 통해 드리프트를 식별하고 지속적 재학습(CT)을 유도한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **PSI (Population Stability Index)**: 기준선 분포와 현재 운영 데이터 분포의 차이를 수치화하는 지표 ($PSI > 0.2$ 시 중대한 드리프트 판정).
- **Slice Analysis**: 전체 평균 정확도에 가려진 특정 사용자 세그먼트나 지역별 국소 성능 하락을 발굴하는 세분화 분석.

</details>

- KS-Test, PSI(인구집단 안정성 지수), KL 발산 등을 활용한 **정량적 통계 거리 측정**
- 지연 정답(Ground Truth) 수집 전 예측값의 편향을 파악하는 **예측 분포(Prediction Drift) 감시**
- 특정 사용자 집단이나 지역별 국소 품질 하락을 탐지하는 **슬라이스 분석(Slice Analysis)**

#### 한줄 요약
- 통계 거리 측정, 예측 분포 감시, 슬라이스 분석을 통해 운영 모델의 성능 저하를 조기 포착한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **드리프트 모니터링 4대 핵심 구조**: Baseline Store(학습 기준선), Telemetry Collector(로그 수집), Label Joiner(정답 결합), Drift Detector/Controller(통계 판정 및 CT 트리거).

</details>

```text
[모델 드리프트 감지 구성]
|-- 기준선 저장소
|-- 텔레메트리 수집기
|-- 정답 결합기
|-- 드리프트 탐지기
`-- 대응 제어기
```

선의 의미: 계층 및 텔레메트리 수집기가 입력과 정답을 모아 정답 결합 엔진을 거쳐 드리프트 탐지기가 기준선과 비교 후 대응 제어기를 구동하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **기준선 저장소 (Baseline)**| 모델 학습 및 검증 시점의 **피처 통계 분포, 상관관계, 성능 기준선(F1, AUC) 보관**| 학습 기준 메트릭 |
| **텔레메트리 수집기** | 실시간 추론 로그의 **입력 피처($X$), 모델 예측값($\hat{Y}$), 슬라이스 메타 수집** | Kafka 스트리밍 |
| **정답 결합기 (Label Joiner)**| 비동기로 수집되는 **실제 결과 정답($Y$)을 과거 예측 로그와 트랜잭션 ID로 결합** | Ground Truth 매핑 |
| **드리프트 탐지기 (Detector)**| KS-Test, PSI 등을 통해 **기준선 대비 통계적 분포 차이 및 성능 저하 유의성 판정** | 통계 가설 검정 |
| **대응 제어기 (Controller)** | 성능 저하 확정 시 **Slack 경보 발송, 이전 모델 롤백, CT 재학습 파이프라인 자동 실행** | CT 자동 트리거 |

#### 한줄 요약
- 기준선 저장소, 텔레메트리 수집기, 정답 결합기, 탐지기, 대응 제어기가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **드리프트 모니터링 5단계**: 로그 수집 $\to$ 통계 검정 $\to$ 지연 정답 결합 $\to$ 드리프트 유형 판정 $\to$ CT 자동 재학습.

</details>

```text
실시간 모델 추론 및 드리프트 모니터링 가동
        │
   1. [로그 수집] 이상 거래 탐지(FDS) 모델의 실시간 입력 피처 50개와 예측 스코어 수집
        │
   2. [통계 검정] 일간 단위로 기준선과 비교하여 결제 금액 피처의 PSI가 0.25를 초과 감지
        │
   3. [정답 결합] 3일 후 카드사에서 확정된 실제 부정 거래 정답 데이터를 과거 예측 로그와 조인
        │
   4. [유형 판정] 실제 F1-Score가 0.92에서 0.78로 하락하여 신종 사기에 의한 Concept Drift 확정
        │
   5. [자동 재학습] Airflow가 최신 30일 데이터를 바탕으로 CT 파이프라인을 기동하여 신규 모델 배포
```

#### 한줄 요약
- 로그 수집 → 통계 검정 → 정답 결합 → 유형 판정 → 자동 재학습 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Data Drift vs Concept Drift vs Prediction Drift**: 입력 분포 변화($P(X)$), 정답 관계 변화($P(Y|X)$), 모델 출력 분포 변화($P(\hat{Y})$).

</details>

| 비교 항목 | 데이터 드리프트 ($P(X)$) | 개념 드리프트 ($P(Y \mid X)$) | 예측 드리프트 ($P(\hat{Y})$) |
|:---|:---|:---|:---|
| 핵심 발생 원인 | **신규 고객 유입 등 입력 피처의 특성 분포 변화**| **경제/규제 변화로 동일 입력에 대한 정답 변화** | **모델 예측 클래스 분류 비율의 비정상적 편향**|
| 감지 가능 시점 | **정답 레이블 없이도 통계 검정(KS-Test)으로 즉시** | **실제 지연 정답(Ground Truth) 결합 후 확인** | **실시간 추론 출력 확률 분포 모니터링으로 즉시** |
| 사용 통계 기법 | **PSI, Kolmogorov-Smirnov (KS-Test), KL 발산** | **F1-Score, AUC, RMSE 실측 성능 지표 하락** | **카이제곱 검정, Jensen-Shannon Divergence** |
| 최적 대응 조치 | 최신 입력 데이터셋 수집 및 파이프라인 점검 | **신규 데이터 기반 모델 지속적 재학습(CT)** | 모델 서빙 입력 데이터 이상 유무 선행 확인 |

#### 한줄 요약
- 정답 전 즉시 감지는 데이터 드리프트, 실질적 성능 하락 확정은 개념 드리프트를 분석한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Hysteresis Threshold**: 주말/이벤트 등 일시적 트래픽 변동을 영구적 드리프트로 오판하지 않도록 일정 기간 이상 지속될 때만 경보를 울리는 필터.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 주말/이벤트 등 일시적 계절성을 드리프트로 오판하여 불필요한 재학습 | **요일/계절별 `다중 Baseline` 구성 및 최소 지속 시간(히스테리시스) 검증** | 오탐(False Alarm) 90% 차단 |
| 지연 정답 수집 지연으로 모델 성능 저하를 수개월간 방치 | **정답 이전 단계에서 `대리 지표(Proxy Metric)` 및 예측 드리프트 감시** | 성능 저하 조기 경보 체계 확보 |
| 전체 평균 지표에 가려져 특정 소수 그룹의 국소 성능 급락 은폐 | **핵심 사용자 세그먼트별 `슬라이스 분석(Slice Analysis)` 필수 적용** | AI 공정성 및 국소 결함 탐지 |
| 대용량 추론 트래픽 전수 감시로 인한 모니터링 인프라 비용 폭증 | **적응형 샘플링(Reservoir Sampling 10%) 및 비동기 배치 검정 적용** | 모니터링 TCO 80% 절감 |

#### 한줄 요약
- 다중 기준선, 대리 지표 감시, 슬라이스 분석, 적응형 샘플링으로 운영한다.

## Ⅶ. 결론

- 분포 변화에는 **통계 검정**, 성능 저하에는 **지연 정답·CT** 적용

#### 한줄 요약
- 모델 모니터링은 통계적 가설 검정과 지연 정답 매핑을 통해 데이터/개념 드리프트를 조기에 감지하고 자동 재학습을 트리거하는 핵심 MLOps 품질 관리 기술이다.
