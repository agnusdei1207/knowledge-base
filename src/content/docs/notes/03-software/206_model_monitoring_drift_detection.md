## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 모니터링 및 드리프트 감지(Model Monitoring & Drift Detection)**: 운영 환경에서 실시간으로 입력되는 피처 데이터, 모델 예측값, 지연 정답(Delayed Label)을 학습 기준선(Baseline)과 통계적으로 비교하여 모델 성능 저하와 데이터 분포 변화를 조기에 감지하고 자동 대응하는 MLOps 품질 관리 체계.
- **데이터 및 개념 드리프트 위험(Data & Concept Drift Risk)**: 소비자 행동 변화, 계절성, 경제 환경 변화로 인해 학습 데이터와 운영 데이터 간의 분포 차이가 발생하여 모델 예측 정확도가 급락하는 위험.

</details>

- 정의/개념: 운영 환경의 입력 데이터, 예측값, 지연 정답을 기준선과 대조하여 **데이터 및 개념 드리프트를 실시간 감시하는 MLOps 품질 관리** 체계
- 배경/필요성: 시장 트렌드 변화 및 계절성 요인으로 인한 **데이터 드리프트(Data Drift), 예측 정확도 급락 및 비즈니스 손실 위험** 직면

#### 한줄 요약

- 통계적 가설 검정(KS-Test, PSI)과 지연 정답 결합을 통해 데이터 드리프트와 개념 드리프트를 조기에 식별하고 지속적 재학습(CT)을 트리거

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 드리프트(Data Drift, $P(X)$ 변화)**: 입력 피처의 통계적 분포가 달라지는 현상(예: 고령 사용자 비율 급증).
- **개념 드리프트(Concept Drift, $P(Y|X)$ 변화)**: 입력 피처와 정답 레이블 간의 관계가 근본적으로 변하는 현상(예: 금리 인상으로 동일 소득자의 대출 상환율 급락).

</details>

- KS-Test, PSI(인구집단 안정성 지수), KL 발산 등을 활용한 **정량적 통계 거리 측정**
- 지연 정답(Delayed Ground Truth)이 수집될 때까지 대리 지표(Proxy Metric)를 활용하는 **예측 분포 감시**
- 특정 사용자 집단이나 지역별 국소 품질 하락을 탐지하는 **슬라이스 분석(Slice Analysis)**

#### 한줄 요약

- 실시간 입력 통계 검정과 지연 레이블 성능 추적을 결합하여 무중단 모델 신뢰성을 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 모니터링 5대 아키텍처 계층**: Baseline Store(학습 기준선), Telemetry Collector(운영 신호 수집), Label Joiner(지연 정답 결합), Drift Detector(통계 검정 엔진), Alert & Trigger Controller(대응 제어기).

</details>

```text
[ 모델 모니터링 및 드리프트 감지(Evidently / Arize) 아키텍처 구조도 ]

 1. [ 기준선 저장소 (Baseline Store) ] ── (학습/검증 시점의 입력 및 예측 분포)
              │
              ▼
 2. [ 텔레메트리 수집기 (Signal Collector: Kafka / S3) ] ────────┐
    • 실시간 추론 입력 X + 예측 결과 Y_pred + 지연 정답 Y_true   │
    └─────────┬───────────────────────────────────────────────────┘
              │ (지연 정답 매핑 결합)
              ▼
 3. [ 정답 결합 엔진 (Label Joiner) ] ───────────────────────────┐
    • 트랜잭션 ID 기반으로 7일 후 확정된 실제 대출 연체 여부 결합│
    └─────────┬───────────────────────────────────────────────────┘
              │
              ▼
 4. [ 드리프트 탐지 엔진 (Drift Detector: KS-Test / PSI / Wasserstein) ]
    • Data Drift ($P(X)$) + Prediction Drift + Concept Drift ($P(Y|X)$)
              │
              ▼
 5. [ 대응 제어기 (Response Controller) ] ───────────────────────┐
    • 임계치 초과 시 알림 발송 ➔ CT 자동 재학습 파이프라인 트리거│
    └─────────────────────────────────────────────────────────────┘
```

선의 의미: 텔레메트리 수집기가 입력과 정답을 모아 정답 결합 엔진을 거쳐 드리프트 탐지기가 기준선과 비교 후 대응 제어기를 구동하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 기준선 저장소 (Baseline) | 모델 학습 및 검증 시점의 **피처 통계 분포, 상관관계, 성능 기준선(F1, AUC) 보관** |
| 텔레메트리 수집기 | 실시간 추론 로그의 **입력 피처($X$), 모델 예측값($\hat{Y}$), 슬라이스 메타데이터 수집** |
| 정답 결합기 (Label Joiner) | 비동기로 수집되는 **실제 결과 정답($Y$)을 과거 예측 로그와 트랜잭션 ID로 매핑 결합** |
| 드리프트 탐지기 (Detector) | KS-Test, PSI 등을 통해 **기준선 대비 통계적 분포 차이 및 성능 저하 유의성 판정** |
| 대응 제어기 (Controller) | 성능 저하 확정 시 **Slack 경보 발송, 이전 모델 롤백, CT 재학습 파이프라인 자동 실행** |

#### 한줄 요약

- 기준선 저장소, 신호 수집기, 정답 결합기, 드리프트 탐지기, 대응 제어기가 유기적으로 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **드리프트 모니터링 및 재학습 5단계 수명주기**: 실시간 추론 로그 수집 $\to$ 통계적 분포 거리 산출 $\to$ 지연 정답 매핑 $\to$ 드리프트 유형 판정 $\to$ 자동 대응 및 기준선 갱신.

</details>

```text
[ 드리프트 감지 및 CT 재학습 피드백 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 실시간 추론 입력 및 예측값 수집    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. KS-Test / PSI 통계 검정 (Data Drift)│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 비동기 실제 정답(Label) 결합       │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 성능 저하 및 개념 드리프트 판정    │
 ├───────────────────┬────────────────────┤
 │ 단순 계절성 변화  │ 실질적 성능 급락   │
 │ • Baseline 갱신   │ • CT 자동 재학습   │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 신규 모델 검증 후 무중단 교체 배포 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 수집: 이상 거래 탐지(FDS) 모델의 실시간 입력 피처 50개와 예측 스코어를 Kafka를 통해 적재.
2. 통계 검정: 일간 단위로 기준선과 비교하여 결제 금액 피처의 PSI(Population Stability Index)가 0.25를 초과하여 경보 발생.
3. 정답 결합: 3일 후 카드사에서 확정된 실제 부정 거래 정답 데이터를 과거 예측 로그와 조인.
4. 유형 판정: 실제 F1-Score가 0.92에서 0.78로 하락하여 신종 사기 수법에 의한 개념 드리프트(Concept Drift)로 최종 확정.
5. 자동 대응: Airflow가 최신 30일 데이터를 바탕으로 CT 파이프라인을 기동하여 신규 모델을 학습시키고 배포.

#### 한줄 요약

- 로그 수집 $\to$ 통계 검정 $\to$ 정답 결합 $\to$ 유형 판정 $\to$ 자동 재학습의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Data Drift vs Concept Drift vs Prediction Drift**: 입력 분포 변화($P(X)$), 정답 관계 변화($P(Y|X)$), 모델 출력 분포 변화($P(\hat{Y})$).

</details>

| 드리프트 유형 | 데이터 드리프트 ($P(X)$) | 개념 드리프트 ($P(Y \mid X)$) | 예측 드리프트 ($P(\hat{Y})$) |
|:---|:---|:---|:---|
| 적용 기준 | 신규 고객군 유입 등 입력 피처의 특성 분포가 변했을 때 | 경제/규제 변화로 동일 입력에 대한 정답 결과가 변했을 때 | 모델 예측값(클래스 분류 비율)이 비정상적으로 쏠릴 때 |
| 핵심 특징 | **정답 레이블 없이도 통계적 가설 검정(KS-Test)으로 즉시 감지** | **실제 지연 정답(Ground Truth)과 결합하여 모델 성능 저하 확정** | **모델 출력 확률 분포의 왜곡을 조기에 파악하는 대리 지표** |
| 한계 | 입력 분포가 바뀌어도 모델 성능에는 영향이 없을 수 있음 | 실제 정답이 들어오기까지 수일~수개월의 감시 지연 발생 | 입력 변화인지 모델 결함인지 원인을 단독으로 규명 불가 |

#### 한줄 요약

- 정답 전 즉시 감지는 데이터 드리프트, 실질적 성능 하락 확정은 개념 드리프트를 분석

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **슬라이스 분석(Slice Analysis)**: 전체 평균 정확도는 95%로 우수해 보이지만 특정 저소득 청년층이나 특정 지역 슬라이스에서 정확도가 50%로 급락하는 숨은 결함을 찾는 분석.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 주말/이벤트 등 일시적 계절성을 드리프트로 오판하여 불필요한 재학습 | **요일/계절별 `다중 Baseline` 구성 및 최소 지속 시간(히스테리시스) 검증** | 오탐(False Alarm) 90% 차단 |
| 지연 정답 수집 지연으로 모델 성능 저하를 수개월간 방치 | **정답 이전 단계에서 `대리 지표(Proxy Metric)` 및 예측 드리프트 감시** | 성능 저하 조기 경보 체계 확보 |
| 전체 평균 지표에 가려져 특정 소수 그룹의 국소 성능 급락 은폐 | **핵심 사용자 세그먼트별 `슬라이스 분석(Slice Analysis)` 필수 적용** | AI 공정성 및 국소 결함 100% 탐지 |

#### 한줄 요약

- 다중 기준선, 대리 지표 감시, 슬라이스 분석을 통해 모니터링의 실효성을 극대화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **자율 복원 MLOps(Self-Healing MLOps)**: 드리프트 감지부터 데이터 수집, 재학습, 검증, 무중단 카나리 배포까지 전 과정이 사람의 개입 없이 자율 동작하는 완성형 AI 시스템.

</details>

- **모델 모니터링 및 드리프트 감지** 기반 배포된 AI 모델의 품질 노후화를 방어하고 생명력을 유지하는 MLOps의 핵심 관측성 체계이며, 통계적 가설 검정과 슬라이스 분석 및 CT 파이프라인 연계를 통해 고신뢰 엔터프라이즈 AI를 완성해야 함

#### 한줄 요약

- 통계적 드리프트 감지와 지연 정답 결합 및 지속적 재학습(CT)을 통해 AI 모델 품질을 완성
