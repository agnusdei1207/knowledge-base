## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **변이 테스트(Mutation Testing)**: 코드에 작은 결함을 의도적으로 넣고 기존 테스트의 실패 여부로 결함 탐지력을 평가하는 시험 기법이다.
- **결함 탐지력**: 테스트가 코드의 잘못된 동작을 실제 실패로 드러내는 능력이다.

</details>

- 정의/개념: **변이 테스트**는 원본 코드에 작은 결함을 인위적으로 주입한 변이체를 만들고 테스트가 이를 탐지하는지 측정하는 시험 기법이다.
- 배경/필요성: 실행 커버리지로 알 수 없는 **결함 탐지력** 평가가 필요하다.

#### 한줄 요약

- 인위적 결함 주입 기반 **테스트 탐지력 평가**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **단일 변경**: 변이본마다 원인 격리가 가능하도록 코드 변경 하나만 적용하는 원칙이다.
- **기준 검증**: 변이 실행 전에 원본 프로그램이 테스트를 정상 통과하는지 확인하는 절차이다.
- **원인 분류**: 생존 변이가 발생한 이유와 시험 비용을 구분해 개선 대상을 찾는 활동이다.

</details>

- **단일 변경**: 변이본마다 코드 변경 하나만을 적용한다.
- **기준 검증**: 원본 통과 후 사멸 여부를 판정한다.
- **원인 분류**: 생존 원인과 실행 비용 함께 분석한다.

#### 한줄 요약

- 단일 변경•기준 검증•**생존 원인 분류**가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **변이 연산자(Mutation Operator)**: 산술•관계•논리 연산자나 구문을 정해진 규칙으로 바꾸는 변환 규칙이다.
- **테스트 스위트(Test Suite)**: 원본과 변이본에 같은 입력과 검증식을 실행하는 테스트 모음이다.
- **사멸 변이(Killed Mutant)**: 변이 때문에 테스트가 실패한 상태다.
- **생존 변이(Survived Mutant)**: 변이 뒤에도 테스트가 계속 통과한 상태다.
- **등가 변이(Equivalent Mutant)**: 관찰 동작이 원본과 같아 사멸시킬 수 없는 변이다.

</details>

```text
                    [원본 프로그램]      [변이 연산자]
                              \          /
                               \        /
                              [변이본 집합]
                                /      \
                               /        \
                  [테스트 스위트]      [결과 분류기]
```

선의 의미: 원본 프로그램과 변이 연산자의 선은 변이본 집합을 만드는 기준과 변경 규칙의 관계, 변이본 집합과 테스트 스위트의 선은 동일 입력•검증식 적용 관계, 변이본 집합과 결과 분류기의 선은 사멸•생존•등가 판정 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 원본 프로그램 | **정상 실행•변이 생성 기준** 제공 |
| 변이 연산자 | **구문 변경 규칙** 제공 |
| 변이본 집합 | **독립 변이본** 실행 대상 관리 |
| 테스트 스위트 | 동일 **입력•검증식** 실행 |
| 결과 분류기 | **사멸•생존•등가** 상태와 점수 관리 |

#### 한줄 요약

- 원본•연산자•변이본•**시험•분류 구조**가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **변이 생성기(Mutant Generator)**: 원본 코드에 변이 연산자를 하나씩 적용해 독립 변이본을 만드는 도구이다.
- **변이 점수(Mutation Score, MS)**: 비등가 변이 중 테스트가 사멸시킨 비율이다.
- **기준 테스트 검증**: 변이 실행 전에 원본 프로그램이 기존 테스트를 정상 통과하는지 확인하는 동작이다.
- **변이 연산자 선택**: 실제 결함 위험을 모사할 구문 변경 규칙을 고르는 동작이다.
- **독립 변이본 생성**: 원인 격리를 위해 변이 연산자 하나만 적용한 실행본을 만드는 동작이다.
- **동일 테스트 스위트 실행**: 각 변이본에 원본과 같은 입력•검증식을 적용하는 동작이다.
- **변이 결과 분류**: 실행 차이를 사멸•생존•등가로 판정하고 변이 점수를 계산하는 동작이다.
- **입력(Input)**: 원본과 변이본에 동일하게 적용하는 시험 자료다.
- **검증식(Assertion)**: 원본과 변이본의 동작 차이를 판정하는 조건이다.
- **사멸 수($K$)**: 테스트가 사멸시킨 변이본 수다.
- **전체 변이 수($M$)**: 생성한 전체 변이본 수다.
- **등가 변이 수($E$)**: 전체 변이 중 등가로 판정한 수다.

</details>

```text
[원본 프로그램•기존 테스트]
           |
           v
+----------------------------+
| 1. 기준 테스트 검증       |---- 실패 ----> [원본•시험 수정]
+----------------------------+
           |
           v
+----------------------------+
| 2. 변이 연산자 선택       |
+----------------------------+
           |
           v
+----------------------------+
| 3. 독립 변이본 생성       |
+----------------------------+
           |
           v
+----------------------------+
| 4. 동일 테스트 스위트 실행|
+----------------------------+
           |
           v
+----------------------------+
| 5. 변이 결과 분류         |
+----------------------------+
           |
     +-----+-----+----------+
     | 사멸      | 생존     | 등가 후보
     v           v          v
[탐지 확인] [시험 보강] [등가성 검토]
```

**동작 원리**

1. **기준 테스트 검증**: 기존 테스트의 원본 통과 확인한다.
2. **변이 연산자 선택**: 결함을 모사할 변경 규칙을 선택한다.
3. **독립 변이본 생성**: 단일 변경으로 생존 원인을 격리한다.
4. **동일 테스트 스위트 실행**: 같은 입력•검증식을 적용한다.
5. **변이 결과 분류**: 사멸•생존•등가 판정한다.

$$MS=\frac{K}{M-E}\times100$$

> 요약: 비등가 생존 변이에 입력•검증식 보강이 핵심이다.

#### 한줄 요약

- 기준 검증•변이 실행•**생존 시험 보강 흐름**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **구조 커버리지(Structural Coverage)**: 테스트가 구문•분기•조건 같은 코드 구조를 실행한 비율이다.

</details>

| 판단 기준 | 뮤테이션 테스트 | 구조 커버리지 |
|:---|:---|:---|
| 적용 기준 | **검증식의 결함 탐지력** 확인 | **미실행 코드 구조** 식별 |
| 핵심 특징 | 결함 주입 후 **사멸•생존** 판정 | 실행된 **구문•분기 비율** 측정 |
| 한계 | **등가 변이•반복 실행** 비용 | 실행만으로 **결함 탐지력** 오판 |

> 요약: 뮤테이션은 탐지력, 커버리지는 실행 범위를 측정한다.

#### 한줄 요약

- 실행 범위는 커버리지, 탐지력은 **뮤테이션**이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **선택적 뮤테이션(Selective Mutation)**: 결함 위험이 큰 코드와 대표 변이 연산자만 골라 실행 비용을 줄이는 방식이다.
- **변이 점수 신뢰성**: 등가 변이를 제외하고 일관된 기준으로 산정한 변이 점수가 탐지력을 정확히 나타내는 정도이다.
- **고위험 생존 변이**: 업무 영향이 큰 코드에서 테스트가 놓친 인위적 결함이다.
- **자동 후보 제거(Automatic Filtering)**: 정적 분석으로 등가 가능성이 큰 변이를 거르는 절차다.
- **수동 검토(Manual Review)**: 사람이 원본과 변이의 동작 동일 여부를 확인하는 절차다.
- **상태 검증식(State Assertion)**: 객체 상태 변화를 확인하는 판정 조건이다.
- **상호작용 검증식(Interaction Assertion)**: 협력 객체 호출과 부작용을 확인하는 판정 조건이다.
- **도메인 결함 기반 변이 연산자**: 반올림•한도•상태 전이처럼 실제 업무에서 발생 가능한 오류를 모사하는 변환 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모든 변이에 전체 테스트를 반복해 실행 시간 증가 | **선택적 뮤테이션**으로 고위험 코드 우선 실행 | **반복 실행 시간** 단축 |
| 등가 변이를 분모에 포함해 변이 점수 왜곡 | **자동 후보 제거•수동 검토** | **변이 점수 신뢰성** 확보 |
| 반환값만 검증해 상태•상호작용 변이 생존 | **결과•상태•상호작용 검증식** 추가 | **생존 변이 탐지력** 향상 |
| 일반 연산자가 불가능한 도메인 상태를 생성 | **도메인 결함 기반 변이 연산자** 선택 | **보강 대상 유효성** 확보 |
| 점수 목표가 저위험 테스트 추가를 유도 | **고위험 생존 변이** 중심 평가 | **테스트 보강 효과** 확보 |

> 적용 사례: 요금 계산기는 반올림•한도 변이가 생존하면 경계 입력과 검증식을 보강

#### 한줄 요약

- 선택적 변이와 **고위험 생존 변이 중심 보강**이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **결함 위험(Defect Risk)**: 변이 시험의 우선 범위를 정하는 영향도다.
- **실행 비용(Execution Cost)**: 변이 시험의 반복 횟수를 정하는 자원 부담이다.
- **변이 시험 범위**: 뮤테이션을 적용할 코드, 연산자, 테스트 집합의 경계이다.

</details>

- **결함 위험**이 큰 코드부터 선택적 변이하고 생존 시험 보강이 핵심이다.

#### 한줄 요약

- 고위험 코드 우선 변이와 **생존 시험 보강**이 핵심이다.
