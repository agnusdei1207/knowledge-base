## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **뮤테이션 테스트(Mutation Testing)**: 소스 코드에 인위적으로 작은 결함(변이체)을 주입한 후, 기존 단위 테스트가 이를 실패로 잡아내는지 검증하는 기법.
- **변이 점수(Mutation Score)**: 생성된 전체 유효 변이체 중 테스트가 성공적으로 사멸(Killed)시킨 변이체의 백분율(%).

</details>

- 정의/개념: 소스 코드에 변이 연산자를 적용해 인위적 결함을 주입하고 단위 테스트의 결함 탐지력을 평가하는 **결함 기반(Fault-based) 테스트 검증 기법**
- 배경/필요성: 단순 코드 커버리지 100% 달성 시에도 **단언문(Assertion) 누락으로 실제 결함을 놓치는 형식적 테스트 한계 해결 불가**

#### 한줄 요약
- 원본 코드에 고의적 결함을 주입하여 단위 테스트 스위트의 실질적 결함 탐지 능력을 정량 측정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Killed vs Survived**: 결함이 주입된 코드를 테스트가 실패로 잡아내면 사멸(Killed), 테스트가 모두 통과해버리면 생존(Survived - 테스트 부실).
- **Equivalent Mutant(등가 변이체)**: 문법은 바뀌었으나 실행 결과는 원본과 동일하여 어떤 테스트로도 사멸시킬 수 없는 변이체.

</details>

- **결함 탐지 능력(Fault Detection Capability)** 을 직접 측정하여 테스트 케이스의 질적 수준 평가
- 실행 결과를 **사멸(Killed), 생존(Survived), 등가 변이체(Equivalent)** 로 명확히 분류
- **변이 점수 산출 공식**: $\text{Mutation Score} = \frac{\text{Killed Mutants}}{\text{Total Mutants} - \text{Equivalent Mutants}} \times 100$

#### 한줄 요약
- 변이체 사멸/생존 분류로 변이 점수를 산출하고 테스트 단언문의 정밀도를 검증한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **변이 연산자(Mutation Operator)**: `+`를 `-`로 변경(산술), `>`를 `<=`로 변경(관계), 조건문 반전 등 정형화된 결함 주입 규칙.

</details>

```text
[뮤테이션 테스트 아키텍처 구조]
|-- 원본 소스 코드 (Production Codebase)
|-- 변이 연산자 엔진 (PITest Bytecode Manipulator)
|   |-- 산술/관계 연산자 교체 (+ <-> -, > <-> <=)
|   |-- 조건문 참/거짓 강제 치환
|   `-- 메서드 리턴값 null 치환
|-- 변이체 집합 (Mutants Pool: 수백~수천 개 결함 바이너리)
`-- 단위 테스트 실행기 (Unit Test Runner)
    |-- [테스트 실패/에러 발생] -> 사멸 (Killed: 결함 탐지 성공)
    `-- [테스트 정상 통과]     -> 생존 (Survived: 테스트 단언문 누락 결함)
```

선의 의미: 계층 및 결함 주입-테스트 실행-사멸 판정 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| **변이 연산자 엔진** | 정적/바이트코드 조작을 통해 **표준 결함 패턴을 소스 코드에 주입** |
| **변이체 집합 (Mutants)** | 변이 연산자가 적용되어 독립적으로 생성된 **결함 포함 가짜 코드** |
| **단위 테스트 스위트** | 생성된 각 변이체를 실행하여 **Assertion 실패를 유발해야 하는 검증 대상** |
| **변이 리포터 (PITest)** | **사멸률(Mutation Score), 생존 변이체 위치 및 커버리지 분석** 리포트 제공 |

#### 한줄 요약
- 변이 연산자 엔진, 변이체 풀, 단위 테스트 실행기, 변이 리포터가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PITest**: Java 바이트코드를 메모리상에서 실시간 변조하여 고속으로 뮤테이션 테스트를 수행하는 프레임워크.

</details>

```text
1. 원본 프로그램 대상 기존 단위 테스트 100% 통과(Green) 확인
        │
   2. PITest가 바이트코드 조작으로 N개의 변이체(Mutant) 생성
        │
   3. 각 변이체마다 연관된 단위 테스트 격리 실행
        │
   단위 테스트가 실패(AssertionError) 또는 타임아웃을 발생시켰는가?
   ┌────┴─────┐
  예           아니오
   │             │
[사멸: Killed]   [생존: Survived]
결함 탐지 성공    테스트 단언문 부실 -> 누락된 Assert 단언문 추가 보강
   │             │
   4. 변이 점수(Mutation Score) 리포트 출력 및 CI 품질 게이트 판정
```

#### 한줄 요약
- 사전 검증 → 변이체 생성 → 격리 실행 → 사멸/생존 판정 → 단언문 보강 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **코드 커버리지 vs 뮤테이션 점수**: 라인이 실행되었는가(양적)와 결함을 잡아낼 수 있는가(질적)의 비교.

</details>

| 비교 항목 | 코드 커버리지 (Code Coverage) | 뮤테이션 점수 (Mutation Score) |
|:---|:---|:---|
| 평가 관점 | 코드가 얼마나 많이 실행되었는가? (**양적 평가**) | 결함을 얼마나 정밀하게 잡아내는가? (**질적 평가**) |
| 단언문(Assert) 검증 | Assert가 0개여도 실행만 되면 100% 달성 | **정밀한 Assert 없이는 점수 0점 (생존율 급증)** |
| 실행 시간 | 1회 실행으로 즉시 측정 (수 초) | **수백 개 변이체 반복 실행으로 수 분 소요** |
| 주 적용 영역 | 전사 CI 빌드 파이프라인 기본 게이트 | **결제, 금융, 원전, 의료 등 고신뢰성 핵심 로직** |

#### 한줄 요약
- 코드 커버리지가 실행 여부의 양적 척도라면, 뮤테이션 점수는 단언문 정밀도의 질적 척도다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **등가 변이체 문제**: `if (a == b)`를 `if (b == a)`로 바꿔도 의미가 같아 절대 실패시킬 수 없는 튜링 완전 언어의 한계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대량 변이체 실행으로 인한 CI 빌드 시간 폭증 | **변경된 Git 커밋 코드만 증분 검증(PITest Delta Analysis)** | 실행 시간 90% 단축 및 CI 통합 |
| 사멸시킬 수 없는 **등가 변이체(Equivalent Mutant)** | 정적 분석 연계 및 `@Suppress` 어노테이션 수동 등록 | 점수 왜곡 방지 및 분석 피로도 제거 |
| 단순 Getter/Setter/DTO 검증으로 리소스 낭비 | **도메인 핵심 비즈니스 로직 클래스만 선별 적용** | 투자 대비 결함 예방 효율 극대화 |
| 무한 루프 변이체로 인한 테스트 멈춤 현상 | **개별 테스트 실행 시간의 2배 초과 시 타임아웃 사멸 처리** | 빌드 파이프라인 블로킹 원천 방지 |

#### 한줄 요약
- 증분 델타 스캔, 등가 변이체 예외 처리, 핵심 도메인 선별, 타임아웃 제어로 실무 최적화한다.

## Ⅶ. 결론

- 코드 커버리지의 맹점을 극복하기 위해 금융/결제 등 미션 크리티컬 도메인은 **뮤테이션 테스트(PITest)** 를 도입하고, **증분 실행 및 생존 변이체 피드백 루프**를 통해 단언문의 질적 완성도 확보

#### 한줄 요약
- 뮤테이션 테스트는 고의적 결함 주입을 통해 테스트 코드 자체의 품질을 검증하는 최고 수준의 소프트웨어 신뢰성 보증 기법이다.
