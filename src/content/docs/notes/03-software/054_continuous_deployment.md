## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **무승인 즉시 배포(No-Touch Continuous Deployment)**: 사람의 수동 승인 단계를 완전히 배제하고 자동화된 검증 파이프라인만으로 실환경에 즉각 배포하는 방식.
- **리드타임 지연 및 롤백 위험(Lead-Time Delay & Rollback Failure)**: 배포 승인을 기다리는 동안 변경 사항이 누적되어 한 번에 배포할 때 장애 원인 분석이 불가능해지는 한계.

</details>

- 정의/개념: CI 테스트 및 품질 게이트를 통과한 아티팩트를 수동 승인 없이 **프로덕션 환경에 즉시 릴리스(No-Touch)**하는 완전 자동화 배포 전략
- 배경/필요성: 수동 릴리스 승인 병목으로 인한 **배포 리드타임 지연 및 대규모 일괄 배포 시 롤백 실패 위험** 직면

#### 한줄 요약

- 품질 게이트·점진적 배포·자동 롤백을 갖춘 완전 자동화 배포로 빠른 시장 피드백 주기를 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **소규모 배치 배포(Small Batch Deployment)**: 변경 범위를 최소화하여 자주 배포함으로써 장애 발생 시 원인 파악과 복구 범위를 최소화하는 배포 원칙.
- **가드레일 지표(Guardrail Metrics)**: 배포 후 에러율·지연 시간 등을 실시간 감시하여 임계값 초과 시 자동 롤백을 실행하는 배포 안전 판단 기준.

</details>

- 수동 승인 없는 **No Human Touch** 완전 자동화 배포
- **소규모 배치 배포**로 배포 단위 최소화, 장애 파급 범위 감소
- **가드레일 지표** 기반 **Auto-Rollback**으로 배포 실패 시 신속한 자동 복구

#### 한줄 요약

- 수동 개입 제거·소규모 배치·자동 롤백으로 고빈도 안전 배포를 실현

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자동 롤백 엔진(Auto-Rollback Engine)**: Prometheus 등 관측 시스템이 배포 후 지표를 실시간 감시하여 가드레일 임계값 초과 시 이전 버전으로 자동 복구하는 배포 안전 장치.

</details>

```text
[ Continuous Deployment 구조 ]
품질 게이트 통과
   │
불변 아티팩트 (컨테이너 이미지)
   │
배포 제어기 (ArgoCD)
   └─ 운영 환경 자동 배포
   │
트래픽 제어기 (카나리/점진 배포)
   └─ 1% → 10% → 100% 점진 노출
   │
관측 시스템 (Prometheus)
   └─ 에러율·지연 시간 실시간 감시
   │
자동 롤백 엔진 (Argo Rollouts)
   └─ 가드레일 임계값 초과 시 즉시 이전 버전 복구
```

선의 의미: 단계 간 화살표는 배포 흐름, 관측 시스템에서 자동 롤백 엔진으로의 화살표는 임계값 초과 시 롤백 트리거 관계

| 구성요소 | 책임 |
|:---|:---|
| **품질 게이트** | 코드 품질·보안 기준 미달 시 배포 차단 |
| **배포 제어기(ArgoCD)** | 새 버전 아티팩트 감지 후 자동 배포 실행 |
| **트래픽 제어기** | 카나리 기반 점진적 트래픽 노출 |
| **관측 시스템** | 에러율·지연 시간·CPU 등 가드레일 지표 실시간 감시 |
| **자동 롤백 엔진** | 가드레일 임계값 초과 시 즉시 이전 버전 자동 복구 |

#### 한줄 요약

- 품질 게이트→자동 배포→점진 노출→관측→자동 롤백으로 안전한 완전 자동화 배포 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **점진적 전달(Progressive Delivery)**: 카나리 배포·피처 플래그로 새 버전을 소수 사용자에게 먼저 노출하고 관측 후 전체로 확대하는 배포 전략.

</details>

```text
1. Git Push → 품질 게이트 통과
   │
   ▼
2. 운영 환경 자동 배포 (ArgoCD가 새 Pod 기동)
   │
   ▼
3. 카나리: 전체 트래픽의 1% 신규 버전으로 라우팅
   │
   ▼
4. 가드레일 지표 감시 (에러율·지연 시간)
   │
   ├─ 정상: 트래픽 10% → 100% 점진 확대
   │
   └─ 이상: 가드레일 임계값 초과 → 자동 롤백 실행
```

**동작 원리**

1. **자동 배포**: 품질 게이트 통과 후 ArgoCD가 새 버전 컨테이너를 기동
2. **점진 노출**: 트래픽을 1%→10%→100% 순으로 단계별 노출하여 장애 파급 최소화
3. **지속 감시**: Prometheus가 에러율·지연 시간·CPU 등 가드레일 지표를 실시간 감시
4. **자동 복구**: 가드레일 임계값 초과 감지 시 Argo Rollouts가 이전 버전으로 즉시 복구

#### 한줄 요약

- 자동 배포→점진 노출→가드레일 감시→정상 확대·이상 즉시 롤백의 안전한 배포 순환 흐름

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **수동 승인 vs 무개입 배포**: Delivery는 운영 배포 직전 수동 승인 단계를 유지하고, Deployment는 품질 게이트 통과 즉시 자동 배포하는 방식의 차이.

</details>

| 비교 항목 | Continuous Delivery | Continuous Deployment |
|:---|:---|:---|
| 수동 개입 | 운영 배포 직전 **수동 승인 필수** | **완전 자동, 수동 개입 없음** |
| 배포 속도 | 승인 대기 시간 발생 | 품질 게이트 통과 즉시 배포 |
| 필수 조건 | 빌드·테스트 자동화 | 테스트 자동화 + 관측 + 자동 롤백 체계 |
| 적합 환경 | 규제 산업·고위험 배포(금융·의료) | 빠른 피드백·SaaS·웹 서비스 |

#### 한줄 요약

- 규제 환경은 수동 승인의 Delivery, 고빈도 배포 환경은 완전 자동화 Deployment 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **하위 호환성(Backward Compatibility)**: 신규 버전 배포 후 이전 버전과의 API·DB 스키마 호환성을 유지하여 롤백 시에도 서비스 연속성을 보장하는 설계 원칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DB 스키마 변경 후 롤백 시 구버전과 스키마 불일치로 장애 | **Expand-Contract 패턴**으로 하위 호환 유지하며 단계적 스키마 변경 | 롤백 시 DB 호환성 보장·2차 장애 방지 |
| 품질 기준 미달 코드가 자동 배포되어 운영 장애 발생 | **Quality Gate** 테스트 커버리지·보안 기준을 엄격히 설정 | 결함 코드의 운영 환경 유입 차단 |
| 자동 배포 후 에러 급증으로 서비스 장애 발생 | **Prometheus + Argo Rollouts** 기반 가드레일 자동 롤백 적용 | 장애 발생 후 신속한 자동 복구로 영향 최소화 |

#### 한줄 요약

- DB 변경은 Expand-Contract로, 코드 품질은 Quality Gate로, 배포 장애는 자동 롤백으로 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지속적 배포 도입 기준**: 자동화 테스트 성숙도·관측 체계·자동 롤백 역량·규제 요구사항을 기준으로 Delivery·Deployment를 선택하는 판단 기준.

</details>

- 관측 체계·자동 롤백·높은 테스트 자동화를 갖춘 SaaS·웹 서비스는 **Continuous Deployment**, 규제 환경은 **Continuous Delivery** 선택

#### 한줄 요약

- 관측·자동 롤백 체계가 완비된 환경에서 Continuous Deployment로 고빈도 안전 배포를 실현
