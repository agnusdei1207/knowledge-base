## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **지속적 배포 (Continuous Deployment)**: 개발자가 코드를 `push`하면, 테스트부터 실운영(Prod) 배포까지 팀장님 결재나 사람 손 1도 안 거치고 로봇이 다이렉트로 쏴버리는 궁극의 자동화이다.
- **지속적 전달(Delivery) vs 지속적 배포(Deployment)**: Delivery는 마지막에 사람이 "배포 버튼"을 눌러야 하지만, Deployment는 코드 퀄리티 게이트만 통과하면 자비 없이 바로 운영 서버에 꽂아버리는 차이가 있다.
- **자동 복구 (Auto-Rollback)**: 봇이 무지성 배포를 때렸는데 에러가 터지면, 1초 만에 감지하고 배포 전 옛날 버전으로 롤백시켜버리는 멱살 잡이 생존 장치이다.

</details>

- 정의: CI 테스트와 품질 검사를 통과한 코드가 사람의 개입(No Human Touch) 없이 100% 자동으로 실운영 서버까지 배포되는 끝판왕 프로세스인 **Continuous Deployment**
- 배경: 매주 밤새서 수동 배포하다가 꼬이는 뻘짓을 막고, **하루에도 수십 번 배포해서 시장 피드백을 초스피드로 땡기기 위함**

#### 한줄 요약

- 개발자가 퇴근 전 커밋 하나 때리면, 봇이 검사하고 운영 서버까지 논스톱으로 꽂아버리는 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **소규모 배치 배포 (Small Batch Deployment)**: 3달 치 코드를 한 번에 배포하면 버그 찾다 피 토하니까, 커밋 1~2개씩 찔끔찔끔 자주 배포해서 장애 영향도를 콩알만 하게 줄이는 기법이다.
- **가드레일 지표 (Guardrail Metrics)**: 배포 직후 CPU가 튀거나 500 에러(Error Rate)가 솟구치는지 감시하다가, 선 넘으면 가차 없이 롤백 스위치를 눌러버리는 킬스위치이다.

</details>

- 팀장 승인 따윈 없는 **No Human Touch (무개입 자동 배포)**.
- 코드 한두 줄 고친 걸 바로 쏘는 **Small Batch Deployment**로 장애 파괴력 최소화.
- 터지면 봇이 알아서 원복하는 **Guardrail Metrics** 기반 **Auto-Rollback** 메커니즘 필수 결합.

#### 한줄 요약

- 사람 손 안 타고, 찔끔찔끔 자주 배포하며, 터지면 봇이 1초 만에 롤백하는 게 생명이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자동 롤백 엔진(Auto-Rollback Engine)**: 프로메테우스(Prometheus)가 새 버전 상태를 째려보다가, 지연 시간(Latency)이 튀는 순간 옛날 버전으로 트래픽을 확 돌려버리는 응급구조대이다.

</details>

```text
[ 지속적 배포 (CD) 십자포화 아키텍처 ]

[ 품질 게이트 (통과) ] ──▶ [ 도커 이미지 (버전 아티팩트) ]
                                        │
                                        ▼ (ArgoCD 자동 배포)
 (장애 나면 롤백) ◀── [ 관측 시스템 ] ◀── [ 트래픽 제어기 (Canary) ]
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **품질 게이트** | 버그나 취약점 있으면 배포봇이 출발 못 하게 멱살 잡고 터트리는 방파제 |
| **버전 아티팩트** | 검증 끝난 순도 100% 불변 도커(Docker) 이미지 |
| **배포 제어기 (ArgoCD)**| 창고에 새 이미지 올라오면 잽싸게 물어다가 K8s에 띄워버리는 봇 |
| **트래픽 제어기** | 새 버전에 유저 다 몰아주지 않고, 1% $\to$ 10% 찔끔 쪼개주는 조절기 |
| **관측 시스템** | 1% 유저한테 에러 터지는지 눈에 불을 켜고 감시하는 CCTV (Prometheus) |
| **자동 롤백 엔진** | "에러 떴다!" 하면 묻지도 따지지도 않고 구버전으로 되돌리는 안전장치 |

#### 한줄 요약

- 이미지 구워서 $\to$ 봇이 배포하고 $\to$ 1%한테만 노출시켜 간을 본 뒤 $\to$ 멀쩡하면 100% 쏜다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **점진적 전달 (Progressive Delivery)**: "자정 배포 시작!" 하고 100% 갈아치우는 게 아니라, Canary나 피처 플래그로 1%한테만 간 보며 천천히 노출시키는 세련된 배포 쫄보 메타이다.

</details>

```text
[ 자동 배포 및 롤백 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. Git Push (개발자 커밋)    │
└──────────────┬───────────────┘
               ▼ (품질 게이트 통과)
┌──────────────────────────────┐
│ 2. 운영 환경 자동 띄우기     │
│ (ArgoCD가 새 버전 Pod 띄움)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 카나리 트래픽 1% 노출     │
│ (일부 유저한테만 간 보기)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 가드레일 CCTV 감시        │
│ (500 에러 솟구치는지 확인)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 판정 (Full 배포 or 롤백)  │
│ (정상이면 100%, 아니면 롤백) │
└──────────────────────────────┘
```

### 동작 원리

1. 품질 게이트 통과: CI 뚫고 배포 준비 끝.
2. 운영 배치: 배포 봇이 신규 버전 컨테이너를 띄움.
3. 간 보기(Canary): 전체 유저 대신 딱 1% 트래픽만 신규 버전으로 쏨.
4. 감시: 1% 유저들이 쓰는 동안 CPU, 에러율(Guardrail)이 멀쩡한지 째려봄.
5. 확대/롤백: 멀쩡하면 트래픽 100% 쏴주고(Full Rollout), 터지면 구버전으로 즉시 원복함.

#### 한줄 요약

- 자동 배포 후 $\to$ 1%한테 노출 $\to$ CCTV로 감시 $\to$ 에러 나면 1초 만에 롤백하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **수동 승인 vs 무개입 배포(Manual Gate vs No Human Touch)**: 팀장님 허락받고 버튼 눌러야 실운영 나가는 게 딜리버리(Delivery), 허락 그딴 거 없이 봇이 알아서 운영에 박아버리는 게 디플로이먼트(Deployment)이다.

</details>

| 비교 항목 | **Continuous Delivery (지속적 전달)** | **Continuous Deployment (지속적 배포)** |
|:---|:---|:---|
| 수동 승인 개입 | **운영 배포 버튼은 팀장님이 직접 누름** | **사람 개입 0% (정책 패스하면 걍 배포)** |
| 배포 속도 | 승인 대기 타느라 시간 까먹음 | **대기 0초, 걍 코딩 끝나면 바로 배포** |
| 필수 생존템 | 빌드/시험 자동화만 잘 되어 있으면 됨 | **자동화 테스트 + CCTV(관측) + 자동 롤백 필수** |
| 추천 서식지 | 털리면 쇠고랑 차는 금융, 의료, 공공기관 | 빨리빨리가 생명인 토스, 넷플릭스, SaaS |

#### 한줄 요약

- 배포 버튼을 팀장님이 누르면 딜리버리, 로봇이 누르면 디플로이먼트다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **하위 호환성 (Backward Compatibility)**: DB 컬럼명 바꾼다고 옛날 거 확 지웠다가, 구버전 앱이 에러 뿜고 뒤지는 참사를 막기 위해, (새 거 추가 $\to$ 둘 다 띄움 $\to$ 헌 거 삭제) 순으로 살살 바꾸는 전략이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 배포했는데 DB 스키마 꼬여서 롤백도 안 되고 뻗음 | DB 변경은 무조건 **하위 호환 유지(Expand-Contract)** | 배포 망해서 롤백해도 DB 때문에 터지는 2차 참사 방어 |
| 허접한 코드 커밋이 운영에 자동 배포돼서 난리 남 | 무자비한 **Quality Gate (테스트 커버리지 90% 이상)** | 똥 코드가 운영까지 살아서 가는 걸 철벽 방어 |
| 봇이 무지성 배포했는데 500 에러 쏟아짐 | **Prometheus + Argo Rollouts 기반 Auto-Rollback** | 장애 나도 1초 만에 원복해서 유저들은 모르게 넘어감 |

#### 한줄 요약

- 자동 배포하려면 테스트 코드를 미친 듯이 짜고, DB 바꿀 땐 구버전도 굴러가게 만들어야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지속적 배포 도입 기준(Continuous Deployment Selection Criteria)**: 장애 나면 회사 망하는 금융권인지, 잠깐 뻗어도 롤백하면 그만인 SaaS인지 각 재서 자동 배포 봇을 켤지 말지 정하는 잣대이다.

</details>

- **지속적 배포 도입 기준** 원칙에 따라, 자동 롤백 감당되는 SaaS는 **Continuous Deployment**, 털리면 경찰서 가는 금융망은 **Continuous Delivery** 채택 기조 확립함

#### 한줄 요약

- 아무나 할 수 있는 게 아니라, 관측 시스템(CCTV)과 롤백 엔진이 완벽한 상남자 기업만 쓴다.
