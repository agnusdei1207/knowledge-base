## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **캐싱 전략(Caching Strategy)**: 원본 데이터 사본을 저장하고 읽기•쓰기•만료•무효화하는 방식을 정해 응답 성능과 신선도를 조절하는 전략이다.

</details>

- 정의/개념: 사본의 읽기•쓰기•만료를 정하는 **캐싱 전략**
- 배경/필요성: 원본 직접 조회만으로는 **반복 입출력•응답 지연 증가**

#### 한줄 요약

- 가까운 사본을 누가 채우고 언제 버리며 원본 변경 뒤 어떻게 맞출지 정해야 빠른 조회가 오래된 답으로 바뀌지 않는다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **요청 병합**: 같은 키의 동시 캐시 미스를 하나의 원본 조회로 합치는 방식이다.
- **부정 캐싱**: 존재하지 않는 결과를 저장해 반복 원본 조회를 줄이는 방식이다.
- **유효 시간(Time To Live, TTL)**: 캐시 항목을 유효한 사본으로 인정할 최대 보존 시간이다.
- **지역성**: 반복 접근 데이터가 가까운 저장소에 있을 가능성이다.
- **재사용**: 저장한 사본을 다시 사용해 원본 입출력과 지연을 줄이는 원리이다.

</details>

- **지역성•재사용** 기반 조회 지연 축소
- **TTL•버전•변경 사건** 기반 신선도 관리
- **요청 병합•부정 캐싱** 기반 원본 보호

#### 한줄 요약

- 인기 상품 사본이 동시에 만료돼도 대표 요청 하나만 원본을 읽고 나머지가 결과를 공유하면 데이터베이스 폭주를 막을 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **무효화 계층**: 무효화 계층은 원본 변경 사건을 받아 낡은 캐시를 삭제하거나 새 버전으로 갱신한다.
- **응용 정책**: 캐시의 읽기•쓰기•무효화 방식을 정하는 구성요소이다.
- **키 정책**: 테넌트•자원•질의•판본을 조합하는 규칙이다.
- **캐시 저장소**: 사본 값•버전•유효 시간과 축출을 관리하는 구성요소이다.
- **요청 병합기**: 같은 키의 동시 미스를 하나의 대표 원본 조회로 합치는 구성요소이다.
- **원본 저장소**: 캐시 사본의 기준 데이터를 제공하는 구성요소이다.
- **보호 제어**: 캐시 장애 시 원본 호출량을 제한하는 구성요소이다.

</details>

```text
캐싱 구조
      |
      +-- [응용•키 정책]
      |
      +-- 빠른 조회 경로
      |         +-- [캐시 저장소]
      |         +-- [요청 병합기]
      |
      +-- 원본•신선도 경로
                +-- [원본•보호 제어]
                +-- [무효화 계층]
```

| 구성요소 | 책임 |
|:---|:---|
| 응용•키 정책 | 키 격리•**읽기•쓰기 방식 결정** |
| 캐시 저장소 | 값•버전•**TTL•축출 관리** |
| 요청 병합기 | 동시 미스•**단일 원본 조회** |
| 무효화 계층 | 변경 사건•**삭제•갱신 전파** |
| 원본•보호 제어 | 기준 데이터•**호출 상한 적용** |

#### 한줄 요약

- 응용이 사본 주소와 정책을 정하고 캐시는 보관하며 무효화 계층이 원본 변경을 알리고 요청 병합이 몰리는 손님을 한 줄로 세운다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **캐시 히트(Cache Hit)**: 유효한 사본을 캐시에서 바로 읽은 결과이다.
- **캐시 미스(Cache Miss)**: 사본이 없거나 만료되어 원본 조회가 필요한 결과이다.
- **요청 병합**: 같은 키의 동시 미스를 하나의 원본 조회로 합치는 처리이다.
- **동기 원본 반영**: 쓰기 성공 전에 캐시와 원본을 함께 갱신하는 처리이다.
- **TTL 지터**: 항목별 만료 시각에 무작위 편차를 더하는 방식이다.

</details>

```text
Cache-Aside 읽기
 |
 +-- 캐시 조회
         |
         +-- 히트 --> 사본 반환
         |
         +-- 미스 --> 같은 키의 요청 병합
                          |
                          +-- 대표 요청만 원본 조회
                          +-- 값•버전•TTL 저장
                          +-- 대기 요청에 결과 공유

Write-Through 쓰기
 |
 +-- 캐시•원본 동기 반영
         |
         +-- 모두 성공 --> 쓰기 완료
         |
         +-- 일부 실패 --> 실패 반환•캐시 무효화
```

#### 한줄 요약

- 사본이 없을 때 첫 요청만 원본을 읽고 값과 버전을 저장하면 뒤따른 요청은 같은 결과를 받아 원본 호출을 반복하지 않는다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **캐시 어사이드(Cache-Aside)**: 애플리케이션이 캐시를 먼저 읽고 미스 시 원본을 조회해 사본을 채우는 전략이다.
- **라이트 스루(Write-Through)**: 쓰기 요청을 캐시와 원본에 동기 반영해 즉시 일치를 유지하는 전략이다.
- **라이트 비하인드(Write-Behind)**: 캐시에 먼저 쓰고 원본에는 비동기로 반영해 쓰기 지연을 줄이는 전략이다.

</details>

| 캐싱 전략 | Cache-Aside | Write-Through | Write-Behind |
|:---|:---|:---|:---|
| 적용 기준 | 일반 **조회 중심 서비스** | 쓰기 직후 **원본 최신성** | 지연 허용 **고빈도 쓰기** |
| 핵심 특징 | 응용의 **미스 적재•무효화** | 캐시•원본 **동기 반영** | 캐시 후 **비동기 원본 반영** |
| 한계 | 무효화 누락•**미스 폭주** | 쓰기 지연•**원본 장애 전파** | 유실•순서•**복구 복잡성** |

#### 한줄 요약

- 조회 중심은 응용이 필요한 값만 채우고 즉시 원본 반영이 필요하면 동기 쓰기, 지연 반영을 허용하면 비동기 쓰기를 제한적으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **동시 만료**: 동시 만료는 인기 키들이 같은 시점에 만료되어 많은 요청이 한꺼번에 원본으로 몰리는 문제다.
- **캐시 관통(Cache Penetration)**: 존재하지 않는 키의 반복 요청이 캐시를 이용하지 못하고 계속 원본에 도달하는 문제이다.
- **차단기(Circuit Breaker)**: 원본 실패가 임계치를 넘으면 호출을 일시 중단해 연쇄 장애를 막는 보호 장치이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 테넌트•질의의 **키 충돌** | 테넌트•조건•**키 정책 버전 포함** | **정보 혼합 방지** |
| 핫 키의 **동시 만료** | TTL 지터•**요청 병합•사전 갱신** | **원본 폭주 방지** |
| 존재하지 않는 **키 반복 조회** | 짧은 부정 캐싱•**호출 제한** | **캐시 관통 완화** |
| 이전 조회의 **새 값 덮어쓰기** | 버전 비교•**조건부 저장** | 오래된 **값 역전 방지** |
| 캐시 장애의 **원본 연쇄 부하** | 원본 호출 상한•**차단기 적용** | 저장소 **장애 확산 억제** |

#### 한줄 요약

- 캐시 전체 장애 때 모든 요청이 캐시를 건너뛰어 원본으로 향하지 않도록 호출 상한과 차단기로 원본의 연쇄 장애를 막아야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **선택 기준**: 조회 시점 적재와 동기 쓰기 일치의 우선순위이다.

</details>

- 조회 중심은 **Cache-Aside**, 즉시 원본 일치는 **Write-Through** 선택

#### 한줄 요약

- 조회 중심은 Cache-Aside로 시작하고 TTL•요청 병합•버전 무효화를 함께 설계해 속도와 원본 보호를 동시에 확보해야 한다.
