## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스 생명주기(Process Lifecycle)**: 프로그램이 태어나서(New) CPU를 받으려고 줄을 서고(Ready), 일하고(Running), 쫓겨나서 쉬다가(Blocked), 죽어서 뼈를 묻는(Terminated) 전체 인생 사이클이다.
- **포크/엑섹(fork() / exec())**: 부모가 자기 몸을 똑같이 복제(fork)해서 자식을 낳은 다음, 자식 뇌를 뜯어고쳐 새로운 프로그램(exec)으로 덮어씌우는 잔인한 창조 스킬이다.
- **좀비 프로세스(Zombie Process)**: 자식이 죽어서 시체가 됐는데 부모가 장례(wait)를 안 치러줘서, 메모리는 비웠는데 커널 호적(PID)에 유령처럼 남아있는 끔찍한 에러 덩어리이다.
- **상태 전이(State Transition)**: 얌전히 줄 서 있던 프로세스가 CPU를 뺏기고, I/O 터져서 대기실로 쫓겨나고, 다시 돌아오는 롤러코스터 같은 신분 변화이다.

</details>

- 정의: 생성부터 준비, 실행, 대기, 종료까지 5단계로 빙글빙글 돌며 OS가 자원을 통제하는 **프로세스 상태 전이 메커니즘**
- 배경: 프로세스마다 상태를 명확히 갈라치지 않으면, 스케줄러가 누가 일할 준비가 됐고 누가 하드디스크 읽느라 멍때리는지 구분할 방법이 없기 때문

#### 한줄 요약

- OS가 프로세스를 태어나게 하고, 일시키고, 재우고, 죽이는 다섯 단계의 상태 통제 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **준비 상태(Ready State)**: "나 일할 준비 다 됐어!" 하고 대기줄(Ready Queue) 맨 앞에 서서 스케줄러의 부름(디스패치)만 눈이 빠지게 기다리는 상태이다.
- **실행 상태(Running State)**: 치열한 경쟁을 뚫고 CPU를 독차지해서 미친 듯이 코드를 연산하며 꿀을 빠는 최고의 전성기이다.
- **대기 상태(Blocked State)**: 디스크에서 파일 읽어오라는 명령을 내린 뒤, CPU 줘도 할 일이 없어서 대기실(Wait Queue)로 쫓겨나 멍때리는 굴욕의 시간이다.

</details>

- 싱글 코어 기준으로 CPU 권력을 독점하는 **실행 상태(Running)**는 오직 단 한 놈뿐임.
- 디스패치만 목빠지게 기다리는 **준비 상태(Ready)**와 이벤트 완료를 기다리며 쫓겨난 **대기 상태(Blocked)**로 줄(큐)을 명확히 이원화함.
- 자식이 먼저 죽으면 부모가 **wait()** 함수를 때려서 시체를 치우고 **좀비 프로세스**를 박멸해야 함.

#### 한줄 요약

- 실행 상태의 놈만 CPU를 쓰고, 나머지는 준비 큐나 대기 큐에서 자기 차례만 하염없이 기다린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **준비 큐(Ready Queue)**: 일할 준비가 끝난 프로세스들이 서로 먼저 CPU를 잡겠다고 아귀다툼하며 줄을 서는 살벌한 대기실이다.
- **대기 큐(Wait/Device Queue)**: 파일 입출력이나 네트워크 응답을 기다리느라 쫓겨난 프로세스들이 모여서 하염없이 멍때리는 귀양지이다.
- **피아이디(PID, Process Identifier)**: OS가 수천 개의 프로세스를 헷갈리지 않게 관리하려고 이마에 찍어버린 고유한 식별 번호표이다.

</details>

```text
[ 프로세스 생명주기 십자포화 상태 전이 파이프라인 ]
                 [ 스케줄러 (통제관) ]
                           │ (명령)
                           ▼
    ┌────── [ PCB (주민등록증 / PID) ] ──────┐
    │                                      │
[ 준비 큐 ]                             [ 대기 큐 ]
(대기실 1)                              (귀양지 2)
    │                                      │
    └─── (디스패치) ──► [ CPU (권력) ] ◄──┘
```

| 구성요소 | 책임 |
|:---|:---|
| **PCB** (주민등록증) | 커널 호적(**PID**), 현재 상태(Ready/Running/Block), 레지스터 덤프를 빼곡히 적어둔 장부 |
| **준비 큐** (Ready Queue) | 스케줄러 정책(우선순위 등)에 따라 CPU를 차지하려고 줄 서 있는 **PCB** 포인터 집합소 |
| OS 스케줄러 | **준비 큐**를 째려보다가 제일 급한 놈을 멱살 잡고 끌어내서 CPU에 꽂아주는 악덕 작업 반장 |
| CPU (실행 코어) | 스케줄러가 꽂아준 프로세스의 명령어(Instruction)를 미친 듯이 갈아 넣으며 연산하는 심장 |
| **대기 큐** (Wait Queue) | 디스크 읽기나 이벤트 응답을 기다리느라 할 일 없는 놈들을 몰아넣고 대기시키는 유배지 |

#### 한줄 요약

- 큐(Queue)에 나열된 장부(PCB)들을 스케줄러가 빼서 CPU에 꽂아주고, 일 없으면 다시 큐로 던진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **디스패치(Dispatch)**: 스케줄러가 대기줄 맨 앞에 있는 놈을 멱살 잡고 끌어내서 "이제 네가 CPU 써라!" 하고 권력을 쥐여주는 특권 부여이다.
- **선점(Preempt / Timeout)**: 할당된 시간(타임 슬라이스)을 다 썼는데도 눈치 없이 안 나가면, 강제로 CPU 권력을 뺏고 뒤통수를 쳐서 다시 줄을 세우는 쫓아내기이다.

</details>

```text
[ 생명주기 5단계 상태 전이(State Transition) 흐름 ]
[ 생성 완료•PCB 등록 ]
          │
          ▼
      [ 준비 상태 ] ◄───────────────┐
          │                         │
          │ 1. 디스패치 (CPU 할당)  │ 2. 선점 (시간 만료, 방 빼!)
          ▼                         │
      [ 실행 상태 ] ────────────────┘
        │      │
        │      └── 3. I/O 대기 전환 (디스크 읽어와!) ──► [ 대기 상태 ]
        │                                                    │
        │                         4. 이벤트 완료 (다 읽었어) │
        │                                                    └──► [ 준비 상태 ]
        │
        └── 5. 프로세스 종료 (exit) ──► [ 종료 상태 ]
```

### 동작 원리

1. 디스패치: 스케줄러가 런 큐에서 놈을 뽑아 실행 상태로 만들고 CPU 권력을 쥐여줌.
2. 선점(Preempt): 정해진 시간(타임 슬라이스)을 다 썼는데 안 나가면 강제로 멱살 잡고 **준비 상태**로 쫓아냄.
3. I/O 대기 전환: 실행 중에 디스크나 네트워크를 요청하면, CPU를 반납하고 **대기 상태**로 유배당함.
4. 이벤트 완료: 요청한 I/O가 끝나면 유배지(대기 큐)에서 풀려나 다시 **준비 상태** 줄에 섬.
5. 프로세스 종료: 모든 코드를 끝마치고 `exit()`을 때려 자원을 뱉어내고 종료 상태로 넘어감.

#### 한줄 요약

- 디스패치로 실행하고, 쫓겨나거나(선점) I/O가 터지면 대기하다가 다 돌면 종료한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고아 프로세스(Orphan Process)**: 자식이 한창 일하고 있는데 낳아준 부모가 먼저 죽어버려서, 천애 고아가 된 채 1번 최고 조상 프로세스(init)한테 강제 입양 당한 불쌍한 프로세스이다.

</details>

| 비교 항목 | **준비 상태** (Ready State) | **실행 상태** (Running State) | **대기 상태** (Blocked State) |
|:---|:---|:---|:---|
| CPU 점유 여부 | 미점유 (스케줄러의 간택만 목빠지게 기다림) | **점유 중** (실제 연산 수행하며 꿀 빠는 중) | 미점유 (CPU 줘도 할 일이 없어 이벤트 완료만 기다림) |
| 상주 큐 위치 | **준비 큐** (Ready Queue) | CPU 코어 위 (Core Register) | **대기 큐** (Wait / Device Queue) |
| 다음 전이 상태 | **실행** (디스패치 당할 때) | **준비** (선점당할 때) / **대기** (I/O 터질 때) | **준비** (I/O 끝나고 깨어날 때) |

#### 한줄 요약

- 준비 상태는 디스패치를, 실행 상태는 선점과 I/O를, 대기 상태는 깨어나기를 기다린다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **웨이트피아이디(waitpid())**: 부모 프로세스가 "내 자식 잘 죽었나?" 하고 장례를 치르기 위해 호출하는 함수로, 이걸 안 쓰면 서버가 좀비 떼에 점령당한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 부모가 장례를 안 치러줘서 호적(PID)에 유령 시체가 쌓이는 **좀비 프로세스** 창궐 | 부모 코드에 `SIGCHLD` 처리와 **웨이트피아이디(waitpid())** 호출을 강제로 박아 넣음 | 썩어가는 PID와 종료 상태 찌꺼기를 깔끔하게 회수해 호적 정리 |
| 외부 서버나 디스크가 고장 나서 대기 상태(Blocked)에 갇혀버린 영구 미아 발생 | I/O 요청 쏠 때 영원히 기다리지 않게 **타임아웃(Timeout)**을 걸어버림 | 무한 대기로 프로세스가 얼어붙는 시스템 멈춤 재앙을 칼같이 커트 |
| 악성 코드가 프로세스를 수만 개씩 찍어내서 폭탄 터트리고 메모리 고갈시킴 | 사용자나 그룹 단위로 한 번에 낳을 수 있는 프로세스 **생성 한도(ulimit)**를 하드 코딩함 | 미친 듯한 번식을 막아내고 운영체제 자원 고갈(OOM) 100% 억제 |

#### 한줄 요약

- 좀비가 창궐하면 웨이트피아이디(waitpid)로 치우고, 무한 대기는 타임아웃으로 잘라버려라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **프로세스 수명주기 관리 기준(Process Lifecycle Management Criteria)**: 프로세스가 태어나고 죽을 때 좀비가 안 남게 장례를 잘 치르고, 대기실에서 얼어 죽지 않게 시간을 통제하는 자원 통제 잣대이다.

</details>

- **프로세스 수명주기 관리 기준** 원칙에 따라, 자식의 시체는 **waitpid()**로 칼같이 회수하고, 장기 대기는 **타임아웃**으로 잘라버리는 채택 기조 확립함

#### 한줄 요약

- 생성과 종료 시 좀비를 차단하고, 각 큐에서 무한 대기가 없도록 엄격하게 상태를 통제해야 한다.
