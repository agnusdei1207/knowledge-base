## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스 생명주기(Process Lifecycle)**: 프로세스가 생성(New)되어 준비(Ready), 실행(Running), 대기(Blocked), 종료(Terminated) 상태를 거치며 자원을 점유 및 반납하는 주기.
- **fork() / exec()**: 부모 프로세스의 주소 공간을 복제(fork)하여 자식을 만들고 새로운 바이너리로 교체(exec) 실행하는 시스템 콜.

</details>

- 정의/개념: **fork() / exec()**로 생성된 프로세스가 준비·실행·대기를 거쳐 종료·회수되기까지 커널이 관리하는 **프로세스 생명주기** 상태 전이
- 배경/필요성: I/O를 기다리는 프로세스가 CPU를 붙잡으면 대기 시간만큼 코어가 놀고, 종료 상태를 회수하지 않으면 PCB·PID가 누수되므로, 상태별 큐로 대기 프로세스를 CPU에서 떼어내고 부모의 회수로 자원 반납을 강제하는 관리가 필요

#### 한줄 요약
- 커널이 프로세스 상태를 구분해 CPU와 I/O 대기를 조정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **디스패치(Dispatch)**: 준비 큐의 최우선 프로세스를 선택하여 CPU 제어권을 부여하고 실행 상태로 전이시키는 동작.
- **좀비 프로세스(Zombie Process)**: 자식 프로세스가 종료되었으나 부모가 wait()으로 종료 상태를 회수하지 않아 PID 테이블에 잔존하는 상태.

</details>

- 단일 CPU 코어 기준 실행 상태(Running) 는 시점당 단 하나의 프로세스에만 배정
- 준비 큐(Ready Queue)와 외부 I/O 대기 큐(Wait Queue)의 큐 이원화 분리 운영
- 부모 프로세스의 `wait()` 시스템 콜을 통한 자식 PCB 회수 및 **좀비 프로세스** 방지

#### 한줄 요약
- 상태를 잘게 나눌수록 전이 관리 비용은 늘지만 그 대가로 대기 중인 프로세스를 CPU에서 떼어낼 수 있으므로, 상태 구분 자체가 유휴 시간을 회수하는 수단이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **준비 큐(Ready Queue)**: 메모리에 적재되어 CPU 할당을 기다리는 프로세스 PCB의 연결 리스트.
- **대기 큐(Wait Queue)**: I/O 완료 또는 동기화 이벤트를 대기하는 프로세스 PCB의 연결 리스트.

</details>

```text
[커널 프로세스 관리 체계]
  │
  ├─ [프로세스 테이블] (PID별 PCB 집합 보관)
  │     └─ [PCB] (프로세스 상태·문맥 관리)
  │
  ├─ [커널 스케줄러] (디스패치 대상 선정)
  │     └─ [준비 큐] (CPU 할당 대기 리스트)
  │
  └─ [이벤트 관리자] (I/O 및 동기화 처리)
        └─ [대기 큐] (이벤트 완료 대기 리스트)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 프로세스 테이블 | PID별 PCB 집합 보관 |
| PCB | 프로세스 상태와 CPU 문맥 보관 |
| 커널 스케줄러 | 준비 큐에서 **디스패치** 대상 선정 |
| 준비 큐 | CPU 할당을 기다리는 PCB 보관 |
| 대기 큐 | I/O·이벤트 완료를 기다리는 PCB 보관 |

#### 한줄 요약
- 상태 전이는 결국 프로세스가 어느 큐에 소속되는지를 바꾸는 일이므로, 대기 큐로의 이동이 곧 CPU를 다른 프로세스에 넘기는 행위가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **선점(Preemption)**: 타임 퀀텀 만료 또는 고우선순위 프로세스 등장 시 실행 중인 CPU를 강제 회수하는 동작.

</details>

```text
프로세스 생성 요청 (fork/exec: New 상태)
        │
   메모리 승인 후 준비 큐 진입 (Ready 상태)
        │
   스케줄러가 디스패치(Dispatch)하여 CPU 할당
        │
   명령어 실행 중 (Running 상태)
   ┌────┴───────────────────────────┐
타임아웃(선점)    I/O 요청 발생       실행 완료 (exit)
   │                  │                  │
준비 큐 복귀      대기 큐로 전이      종료 상태 (Terminated)
(Ready)          (Blocked 상태)          │
   ▲                  │             부모가 wait() 호출하여
   │             I/O 완료 인터럽트   자원과 PCB 회수
   └──────────────────┘ (Wakeup)
```

분기 결과: 타임아웃 **선점**은 문맥만 저장하고 준비 큐로 돌아가 즉시 CPU를 다시 다투지만, I/O 요청은 완료 인터럽트가 올 때까지 대기 큐에서 스케줄 대상에서 빠지고, exit는 부모의 wait() 회수 전까지 PCB만 남긴다.

#### 한줄 요약
- 준비 큐 복귀와 대기 큐 이동은 같은 실행 중단이지만 전자는 곧바로 CPU를 다시 다투고 후자는 외부 이벤트가 올 때까지 경쟁에서 빠지므로, 자원을 붙잡는 시간이 달라진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **종료 상태(Terminated State)**: 실행을 마친 프로세스가 부모의 상태 회수를 기다리며 종료 정보만 보존하는 상태.

</details>

| 프로세스 상태 | 커널 위치 | 다음 전이 조건 |
|:---|:---|:---|
| 생성(New) | 프로세스 테이블 등록 전후 | 메모리 승인 후 준비 상태 진입 |
| 준비(Ready) | **준비 큐** 대기 | 디스패치 후 실행 상태 진입 |
| 실행(Running) | CPU 코어 점유 | 선점은 준비, I/O는 대기 상태 전이 |
| 대기(Blocked) | **대기 큐** 대기 | 이벤트 완료 후 준비 상태 복귀 |
| 종료(Terminated) | **종료 상태**로 종료 코드 보존 | 부모 회수 후 PCB 해제 |

#### 한줄 요약
- 준비는 CPU를 기다리고, 실행은 연산하며, 대기는 I/O 완료 후 준비 상태로 복귀한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **waitpid()**: 자식 프로세스의 종료 상태를 감시하고 자원을 비동기로 회수하는 시스템 콜.
- **ulimit(User Limit)**: 단일 사용자 또는 프로세스가 생성할 수 있는 최대 프로세스 수(nproc)를 제한하는 커널 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 종료 상태 미회수로 **좀비 프로세스 누적** | `SIGCHLD`와 **waitpid** 기반 비동기 회수 | PCB 정리·PID 고갈 방지 |
| I/O 지연으로 대기 상태 누적 | 논블로킹 I/O·타임아웃 설정 | 장기 대기 제한·가용성 유지 |
| 무한 포크로 프로세스 폭증 | **ulimit** nproc 한도 설정 | 프로세스 수 제한·OS 마비 방지 |
| 부모 종료로 고아 프로세스 잔존 | PID 1 자동 입양·상태 회수 | 메모리·파일 디스크립터 누수 방지 |

#### 한줄 요약
- 좀비·고아 프로세스와 무한 대기는 모두 종료 신호를 회수할 주체가 없어서 생기므로, waitpid 회수와 I/O 타임아웃으로 회수 책임을 명시하고 nproc 한도로 최악의 확산 범위를 미리 묶는다.

## Ⅶ. 결론

- 운영체제 자원 관리 및 프로세스 제어의 핵심 기본 라이프사이클 모델로 확립되었으며, 실무 대규모 컨테이너/서버 환경에서는 자식 프로세스 종료 상태의 완벽한 회수를 위한 `waitpid()`/`SIGCHLD` 핸들러 구현, 포크 폭탄 방지를 위한 `cgroups`/`ulimit(nproc)` 제어 및 컨테이너 PID 1 init 프로세스(Tini/dumb-init) 적용을 통해 좀비/고아 누수를 원천 차단

#### 한줄 요약
- 종료된 자식은 waitpid로 회수하고, 생성 폭증은 nproc 한도로 제한한다.
