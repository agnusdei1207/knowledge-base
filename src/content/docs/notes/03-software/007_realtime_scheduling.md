## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 스케줄링**: WCET·주기·마감시간으로 실행 순서를 결정하는 RTOS 기법.
- **WCET(Worst-Case Execution Time)**: 캐시 미스, 인터럽트 등 최악의 시스템 상태에서 태스크가 소비할 수 있는 최대 실행 시간.

</details>

- 정의/개념: 태스크의 **WCET**(최악 실행 시간)과 주기를 분석하여 마감기한 내 완수를 보장하는 **실시간 스케줄링**(RM/EDF) 기법
- 배경/필요성: 범용 시분할 스케줄러는 평균 응답시간을 최적화할 뿐 개별 태스크의 완료 시점을 보장하지 않아 마감시간(Deadline) 초과가 확률적으로 발생하므로, WCET·주기 기반 이용률 검증을 진입 단계에 두어 최악 조건에서도 마감을 보장하는 스케줄러가 필요

#### 한줄 요약
- 스케줄 가능성 검증 후 RM 또는 EDF로 마감시간 준수를 관리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스케줄 가능성 검증(Schedulability Test)**: 태스크 집합의 총 CPU 이용률($U = \sum C_i/T_i$)과 알고리즘 상한을 비교하여 마감시간 준수를 수학적으로 증명하는 기법.
- **이용률 상한**: 단일 선점 CPU의 가정 아래 RM·EDF 수용 여부를 판정하는 기준.
- **RM(Rate Monotonic)**: 주기가 짧은 태스크에 높은 고정 우선순위를 부여하고 총 이용률이 $n(2^{1/n}-1)$ 이내면 마감을 보장하는 정적 우선순위 실시간 알고리즘.
- **EDF(Earliest Deadline First)**: 절대 마감시간이 가장 가까운 태스크에 최고 우선순위를 동적으로 부여하여 총 이용률 1 이하이면 마감을 보장하는 알고리즘.

</details>

- **WCET**와 주기를 기반으로 사전에 수용 제어(Admission Control) 및 **스케줄 가능성 검증** 수행
- 주기가 짧을수록 높은 고정 우선순위를 부여하는 정적 **RM(Rate Monotonic)** 알고리즘
- 마감기한이 가장 임박한 태스크에 최고 우선순위를 동적 배정하는 **EDF(Earliest Deadline First)**

#### 한줄 요약
- 사전 이용률 검증은 수용 가능한 부하를 스스로 낮추는 대신 통과한 태스크의 마감을 보장하므로, 결정성은 평균 이용률을 내주고 얻는 속성이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **수용 제어(Admission Control)**: 런타임에 신규 태스크가 유입될 때 이용률 상한을 검증하여 기존 태스크의 마감시간을 파괴하지 않을 때만 진입을 허용하는 모듈.

</details>

```text
[실시간 스케줄링 체계]
  │
  ├─ [태스크 프로파일러] (WCET·주기·마감시간 분석)
  │
  ├─ [수용 제어 엔진] (스케줄 가능성 사전 검증)
  │     ├─ [RM 검증식] (이용률 상한 n(2^(1/n)-1))
  │     └─ [EDF 검증식] (총 이용률 합 <= 1.0)
  │
  ├─ [우선순위 준비 큐] (정책별 정렬 큐)
  │     ├─ [RM 정적 큐] (주기 오름차순 정적 우선순위)
  │     └─ [EDF 동적 큐] (마감시간 오름차순 동적 갱신)
  │
  └─ [실시간 디스패처] (즉각 선점 및 CPU 이양)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 태스크 프로파일러 | 정적 분석으로 **WCET**·주기·마감시간 도출 |
| 수용 제어 엔진 | **이용률 상한**을 검증하는 **수용 제어** 판정 |
| RM 정적 큐 | 주기가 짧은 태스크에 높은 우선순위 부여 |
| EDF 동적 큐 | 절대 마감시간이 임박한 태스크 우선 배치 |
| 실시간 디스패처 | 고우선순위 도착 시 선점과 문맥 전환 |

#### 한줄 요약
- 수용 제어가 실행 전에 이용률 조건을 검사해 마감 보장의 책임을 런타임이 아닌 진입 시점으로 옮기므로, 통과한 태스크 집합에 대해서만 결정성이 성립한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 저우선순위 작업이 공유 자원 락을 쥔 상태에서 중간 작업이 CPU를 선점하여 고우선순위 작업이 무한 지연되는 현상.

</details>

```text
실시간 주기 태스크 도착 (WCET C, 주기 T)
        │
   수용 제어 엔진이 CPU 이용률 상한을 검증
   ┌────┴─────┐
  초과         이용률 상한 이내 통과
   │             │
수용 거부         알고리즘 정책에 따른 우선순위 큐 배치
(Reject)         ┌──┴───┐
                 [RM 정책]  [EDF 정책]
                  │          │
                 주기 기준   절대 마감시간 기준
                 정적 고정   동적 우선순위 갱신
                  │          │
                  └──┬───────┘
                     │
         현재 실행 중인 태스크보다 우선순위가 높은가?
         ┌───────────┴───────────┐
        예                       아니오
         │                         │
      즉시 선점(Preemption)        현재 태스크 계속 실행
      후 CPU 이양
```

분기 결과: 이용률 초과 태스크는 진입 자체가 거부되고, 통과한 태스크는 RM이면 주기로 고정된 우선순위를, EDF면 도착마다 재계산되는 우선순위를 받아 더 높을 때만 선점하므로 선점 판단 비용은 EDF 쪽이 크다.

#### 한줄 요약
- 이용률 검증에서 걸러진 태스크 집합에 대해서만 마감이 보장되므로, 실행 중의 선점 판단보다 진입 시점의 수용 여부가 결정성을 좌우한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도미노 효과(Domino Effect)**: EDF 환경에서 일시적 과부하 발생 시 한 태스크의 마감 실패가 후속 태스크들의 연쇄 마감 실패로 이어지는 현상.

</details>

| 실시간 알고리즘 | Rate Monotonic (RM) | Earliest Deadline First (EDF) | LLF (Least Laxity First) |
|:---|:---|:---|:---|
| 우선순위 방식 | 정적 우선순위 (주기 반비례) | 동적 우선순위 (마감시간 임박순) | 동적 우선순위 (여유시간 최소순) |
| 충분 이용률 조건 | $n(2^{1/n}-1)$ | $U \le 1$ | 여유시간 기반 판정 |
| 과부하 시 동작 | 저우선순위 태스크만 안정적 드롭 | **도미노 효과**(연쇄 마감 실패) | 잦은 우선순위 역전으로 스래싱 |
| 적용처 | 자동차 엔진 제어, 항공 항법 (안전 필수) | 멀티미디어 스트리밍, 통신 패킷 처리 | 이론적 연구 및 특수 제어 시스템 |

#### 한줄 요약
- 안전성과 예측 가능성은 RM이, CPU 자원 활용률 극대화는 EDF가 우수하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **PIP(Priority Inheritance Protocol)**: 공유 자원을 쥔 저우선순위 태스크의 우선순위를 대기 중인 고우선순위 수준으로 임시 상향시키는 프로토콜.
- **PCP(Priority Ceiling Protocol)**: 자원별로 접근 가능한 최고 우선순위를 사전 설정하여 교착상태와 우선순위 역전을 동시 방지하는 기법.
- **CBS(Constant Bandwidth Server)**: 태스크마다 예산(Q)과 주기(P)로 CPU 대역폭을 예약하고 예산을 소진하면 마감시간을 뒤로 미뤄 과부하가 다른 태스크로 전파되지 않게 격리하는 EDF 기반 서버.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 뮤텍스 경합의 **우선순위 역전** | **PIP** 또는 **PCP** 적용 | 고우선순위 태스크의 블로킹 상한 관리 |
| EDF 과부하 시 발생하는 연쇄 마감 실패 **도미노 효과** | **CBS**(Constant Bandwidth Server) 기반 CPU 대역폭 격리 | 비정상 태스크 격리 및 핵심 제어 태스크 보호 |
| 인터럽트 지연과 OS 오버헤드의 WCET 오차 | OS 틱·ISR 시간을 **WCET** 마진에 반영 | 스케줄 가능성 분석의 누락 위험 감소 |
| 비주기적 긴급 이벤트의 처리 지연 | Sporadic Server·Deferrable Server 배치 | 비주기 작업의 CPU 대역폭 예약 |

#### 한줄 요약
- 마감 보장은 평균 이용률을 희생해야 얻어지므로, WCET 마진과 CBS로 최악 조건 기준의 자원을 예약하고 우선순위 역전은 PIP·PCP로 지연 상한을 계산 가능하게 만든다.

## Ⅶ. 결론

- 임베디드 제어(AUTOSAR/RTOS), 로보틱스 및 통신 시스템의 핵심 결정론적 실시간 스케줄링 프레임워크로 확립되었으며, 실무에서는 안전 필수 하드 실시간(Hard RT) 시스템에 정적 우선순위 기반 RM과 우선순위 천장 프로토콜(PCP), 자원 이용률 극대화가 필요한 소프트 실시간(Soft RT)에는 EDF와 과부하 격리를 위한 CBS(Constant Bandwidth Server)를 결합하여 설계

#### 한줄 요약
- 실시간 스케줄링은 수학적 스케줄 가능성 증명과 우선순위 역전 방지 프로토콜의 결합을 통해 완성된다.
