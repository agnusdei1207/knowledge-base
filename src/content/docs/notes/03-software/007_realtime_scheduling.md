## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 스케줄링(Real-Time Scheduling)**: 연산 결과의 정확성뿐만 아니라 지정된 마감 시간(Deadline) 내 완료 여부가 시스템의 올바름을 결정하는 안전 임계 환경에서 CPU 자원을 배분하는 스케줄링 기법.
- **RM(Rate Monotonic)**: 주기가 짧은 태스크일수록 고정적으로 높은 우선순위를 부여하는 정적 선점 스케줄링 알고리즘.
- **EDF(Earliest Deadline First)**: 현재 시점에서 마감 시간이 가장 임박한 태스크에게 최고 우선순위를 동적으로 부여하는 선점 스케줄링 알고리즘.
- **수용 제어(Admission Control)**: 신규 태스크 수용 시 전체 이용률이 스케줄 가능성 한계를 초과하는지 사전 검증하여 수용 여부를 결정하는 기법.

</details>

- 정의/개념: 태스크의 **최악 실행 시간(WCET)**·주기·마감 시간을 기반으로 **수용 제어**와 우선순위 배분을 통해 마감 시간을 보장하는 **실시간 스케줄링 알고리즘**
- 배경/필요성: 범용 OS의 처리량 위주 스케줄링은 마감 시간 절대 준수를 보장할 수 없으므로, **WCET 기반 스케줄 가능성 검증 및 마감 시간 보장 체계 필수**

#### 한줄 요약

- WCET·주기·마감 시간을 사전 분석하여 스케줄 가능성을 검증하고 마감 시간을 보장하는 실시간 스케줄링 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 캐시 미스·메모리 지연 등 최악의 하드웨어 상태에서 태스크가 소요하는 최대 실행 시간.
- **스케줄 가능성 검증(Schedulability Test)**: 태스크 집합의 전체 CPU 이용률과 알고리즘별 이용률 상한을 비교하여 마감 시간 보장 가능 여부를 확인하는 분석.

</details>

- **WCET**·주기·마감 시간을 입력으로 **스케줄 가능성 검증** 후 태스크 수용 결정
- 고정 우선순위 기반 **RM**과 동적 마감 시간 기반 **EDF**로 정책 구분
- **수용 제어**로 런타임 전에 이용률 한계 초과 여부를 사전 차단

#### 한줄 요약

- WCET 기반 스케줄 가능성 검증으로 태스크를 사전 수용 결정하고 마감 시간을 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이용률 상한(Utilization Bound, U)**: 스케줄링 알고리즘이 마감 시간을 100% 보장할 수 있는 CPU 이용률 한계값으로, RM은 $n(2^{1/n}-1)$, EDF는 1.0.

</details>

```text
[ 실시간 스케줄링 구조 ]
태스크 명세 (WCET, 주기, 마감 시간)
   │
   ▼
수용 제어 (Admission Control)
├─ 이용률 계산: U = Σ(Ci/Ti)
├─ RM: U ≤ n(2^(1/n)-1) 검증
└─ EDF: U ≤ 1.0 검증
   │
   ▼
우선순위 준비 큐
├─ RM: 주기 오름차순 정적 우선순위 배치
└─ EDF: 마감 시간 오름차순 동적 우선순위 배치
   │
   ▼
선점 스케줄러 (높은 우선순위 태스크 도착 시 즉시 선점)
```

선의 의미: 가지(`├─`, `└─`)는 수용 제어·큐 정렬 방식에 따른 RM/EDF 분기 관계

| 구성요소 | 책임 |
|:---|:---|
| 태스크 명세 | **WCET**·주기·마감 시간 제공 |
| 수용 제어 | **이용률 상한** 기반 태스크 수용 가능 여부 사전 검증 |
| 우선순위 준비 큐 | RM은 정적 주기 순, EDF는 동적 마감 순 배치 |
| 선점 스케줄러 | 고우선순위 태스크 도착 시 현재 실행 태스크 즉시 선점 |

#### 한줄 요약

- 수용 제어가 이용률 상한을 검증하고 통과한 태스크만 우선순위 큐에 배치하여 선점 스케줄링 수행

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 고우선순위 태스크가 저우선순위 태스크가 보유한 뮤텍스를 대기하는 동안 중간 우선순위 태스크에게 선점당해 마감 시간을 놓치는 현상.

</details>

```text
신규 태스크 도착
   │
   ▼
1. 수용 제어 (이용률 상한 검증)
├─ 초과: 수용 거부
└─ 통과: 큐 배치
         │
         ▼
      2. 우선순위 결정
      ├─ RM: 주기 기반 정적 우선순위 배정
      └─ EDF: 마감 시간 기반 동적 우선순위 배정
         │
         ▼
      3. 선점 스케줄러 실행
      ├─ 현재 실행 태스크 < 신규 태스크 우선순위: 선점
      └─ 현재 실행 태스크 ≥ 신규 우선순위: 계속 실행
         │
         ▼
      4. 마감 시간 감시·과부하 처리
```

**동작 원리**

1. **수용 제어**: 신규 태스크의 WCET과 주기로 이용률을 계산하여 알고리즘별 상한 내에서만 수용
2. **우선순위 결정**: RM은 주기 기반 정적 우선순위 고정, EDF는 실행 시점의 마감 시간으로 동적 우선순위 갱신
3. **선점 스케줄러**: 더 높은 우선순위 태스크 도착 시 현재 실행 태스크를 즉시 선점하여 CPU 이양
4. **마감 감시**: 런타임 중 마감 시간 미준수 위험 시 중요도 낮은 태스크를 중단하여 핵심 태스크 보호

#### 한줄 요약

- 수용 제어로 입장 검증 후 우선순위를 결정하고, 선점으로 마감 시간을 보장하며 과부하 시 중요도 낮은 태스크를 중단

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도미노 효과(Domino Effect)**: EDF 환경에서 과부하 시 한 태스크의 마감 시간 초과가 연쇄적으로 후속 태스크의 마감 시간 초과를 유발하는 현상.

</details>

| 비교 항목 | RM (Rate Monotonic) | EDF (Earliest Deadline First) |
|:---|:---|:---|
| 적용 기준 | 주기 고정·예측 가능한 마감 보장 요구 시 | CPU 이용률 최대화·혼합 마감 요구 시 |
| 핵심 특징 | 주기 짧은 태스크에 **정적** 최고 우선순위 고정 | 마감 임박 태스크에 **동적** 최고 우선순위 부여 |
| 한계 및 위험 | **이용률 상한** ~69%로 CPU 가용률 제한 | 과부하 시 **도미노 효과**로 연쇄 마감 실패 |

#### 한줄 요약

- 예측 가능성 중시 고정 주기 환경은 RM, CPU 가용률 최대화·혼합 마감은 EDF 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 상속 프로토콜(Priority Inheritance Protocol, PIP)**: 뮤텍스를 보유한 저우선순위 태스크의 우선순위를 대기 중인 최고 우선순위 태스크 수준으로 임시 상향하여 **우선순위 역전**을 방지하는 기법.
- **우선순위 상한 프로토콜(Priority Ceiling Protocol, PCP)**: 자원에 접근 가능한 최고 우선순위를 상한으로 설정하여 우선순위 역전과 교착 상태를 동시에 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 뮤텍스 대기로 고우선순위 태스크에 **우선순위 역전** 발생 | **PIP** 또는 **PCP** 적용 | 고우선순위 태스크 대기 시간 최소화 및 마감 보장 |
| EDF 과부하 시 연쇄 마감 실패 **도미노 효과** 발생 | **수용 제어** 강화 및 중요도 낮은 태스크 선별 중단 | 핵심 태스크 마감 시간 보장 |
| 운영체제 오버헤드 미반영으로 **WCET** 분석 오차 발생 | 운영체제 오버헤드를 WCET에 포함하여 보수적 계산 | 스케줄 가능성 분석 정확도 향상 |

#### 한줄 요약

- 우선순위 역전은 PIP/PCP로, 과부하 도미노는 수용 제어로, WCET 오차는 오버헤드 포함 보수적 계산으로 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실시간 스케줄링 선택 기준**: 고정 주기·예측 가능성 요구(RM)와 CPU 이용률 최대화 요구(EDF) 중 우선 제약으로 알고리즘을 결정하는 기준.

</details>

- 예측 가능한 과부하 처리 및 안전 임계 환경은 **RM**, CPU 이용률 최대화 필요 시 **EDF** 선택

#### 한줄 요약

- 예측 가능성과 과부하 안전성이 우선이면 RM, CPU 가용률 극대화가 우선이면 EDF를 적용
