## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 스케줄링(Real-Time Scheduling)**: 태스크의 실행 시간(WCET), 주기(Period), 마감시간(Deadline)을 분석하여 정해진 기한 내 완수를 100% 보장하는 RTOS 기법.
- **WCET(Worst-Case Execution Time)**: 캐시 미스, 인터럽트 등 최악의 시스템 상태에서 태스크가 소비할 수 있는 최대 실행 시간.

</details>

- 정의/개념: 태스크의 **최악 실행 시간(WCET)** 과 주기를 분석하여 마감기한 내 완수를 보장하는 **실시간 스케줄링(RM/EDF)** 기법
- 배경/필요성: 범용 OS의 공정 스케줄링으로는 **미션 크리티컬 제어의 마감기한 초과(Deadline Miss) 및 시간 결정론 보장 불가**

#### 한줄 요약
- 사전 스케줄 가능성 검증을 거쳐 정적(RM) 또는 동적(EDF) 방식으로 마감시간 내 실행을 확정 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스케줄 가능성 검증(Schedulability Test)**: 태스크 집합의 총 CPU 이용률($U = \sum C_i/T_i$)과 알고리즘 상한을 비교하여 마감시간 준수를 수학적으로 증명하는 기법.
- **이용률 상한(Utilization Bound)**: RM은 $n(2^{1/n}-1) \approx 69.3\%$, EDF는 $100\%$ CPU 이용률까지 마감시간을 보장함.

</details>

- **WCET**와 주기를 기반으로 사전에 수용 제어(Admission Control) 및 **스케줄 가능성 검증** 수행
- 주기가 짧을수록 높은 고정 우선순위를 부여하는 정적 **Rate Monotonic(RM)** 알고리즘
- 마감기한이 가장 임박한 태스크에 최고 우선순위를 동적 배정하는 **EDF(Earliest Deadline First)**

#### 한줄 요약
- 사전 이용률 검증으로 입장을 통제하고, 정적 주기(RM) 또는 동적 마감(EDF) 우선순위로 선점 실행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **수용 제어(Admission Control)**: 런타임에 신규 태스크가 유입될 때 이용률 상한을 검증하여 기존 태스크의 마감시간을 파괴하지 않을 때만 진입을 허용하는 모듈.

</details>

```text
[실시간 스케줄러 아키텍처]
|-- 태스크 명세 (WCET $C_i$, 주기 $T_i$, 마감시간 $D_i$)
|-- 수용 제어 엔진 (Admission Control)
|   |-- RM 검증식 : $\sum (C_i/T_i) \le n(2^{1/n}-1)$
|   `-- EDF 검증식 : $\sum (C_i/T_i) \le 1.0$
|-- 우선순위 준비 큐
|   |-- RM 큐 : 주기 오름차순 정적 우선순위 ($T_1 < T_2 < T_3$)
|   `-- EDF 큐 : 마감시간 오름차순 동적 우선순위 ($D_1 < D_2 < D_3$)
`-- 실시간 선점 디스패처 (고우선순위 도착 시 즉시 Preemption)
```

선의 의미: 계층 및 스케줄 가능성 검증 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| 태스크 프로파일러 | 정적 타이밍 분석으로 각 작업의 **WCET** 및 주기 파라미터 도출 |
| **수용 제어 엔진** | 신규 태스크 진입 시 **이용률 상한(Utilization Bound)** 검증 및 승인 여부 판정 |
| RM 정적 큐 | 주기가 짧은 주기적 태스크에 높은 정적 우선순위를 부여하여 관리 |
| EDF 동적 큐 | 매 틱마다 절대 마감시간을 재계산하여 가장 임박한 태스크를 헤드에 배치 |
| 실시간 디스패처 | 고우선순위 태스크 도착 시 100ns 단위 초저지연 선점 문맥 전환 수행 |

#### 한줄 요약
- 태스크 명세, 수용 제어 엔진, RM/EDF 우선순위 큐, 실시간 디스패처가 결합된 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 저우선순위 작업이 공유 자원 락을 쥔 상태에서 중간 작업이 CPU를 선점하여 고우선순위 작업이 무한 지연되는 현상.

</details>

```text
실시간 주기 태스크 도착 (WCET C, 주기 T)
        │
   수용 제어 엔진이 CPU 이용률 상한을 검증
   ┌────┴─────┐
  초과         이용률 상한 이내 통과
   │             │
수용 거부         알고리즘 정책에 따른 우선순위 큐 배치
(Reject)         ┌──┴───┐
                 [RM 정책]  [EDF 정책]
                  │          │
                 주기 기준   절대 마감시간 기준
                 정적 고정   동적 우선순위 갱신
                  │          │
                  └──┬───────┘
                     │
         현재 실행 중인 태스크보다 우선순위가 높은가?
         ┌───────────┴───────────┐
        예                       아니오
         │                         │
      즉시 선점(Preemption)        현재 태스크 계속 실행
      후 CPU 이양
```

#### 한줄 요약
- 이용률 검증 → RM/EDF 우선순위 부여 → 우선순위 비교 선점 → 실행 및 마감 준수 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도미노 효과(Domino Effect)**: EDF 환경에서 일시적 과부하 발생 시 한 태스크의 마감 실패가 후속 태스크들의 연쇄 마감 실패로 이어지는 현상.

</details>

| 실시간 알고리즘 | Rate Monotonic (RM) | Earliest Deadline First (EDF) | LLF (Least Laxity First) |
|:---|:---|:---|:---|
| 우선순위 방식 | **정적 우선순위 (주기 반비례)** | **동적 우선순위 (마감시간 임박순)** | 동적 우선순위 (여유시간 최소순) |
| 최대 CPU 이용률 | $n(2^{1/n}-1) \approx 69.3\%$ (보수적) | **최대 100% (이론상 완전 활용)** | 최대 100% |
| 과부하 시 동작 | 저우선순위 태스크만 안정적 드롭 | **도미노 효과 (연쇄 마감 실패)** | 잦은 우선순위 역전으로 스래싱 |
| 적용처 | 자동차 엔진 제어, 항공 항법 (안전 필수) | 멀티미디어 스트리밍, 통신 패킷 처리 | 이론적 연구 및 특수 제어 시스템 |

#### 한줄 요약
- 안전성과 예측 가능성은 RM이, CPU 자원 활용률 극대화는 EDF가 우수하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **PIP(Priority Inheritance Protocol)**: 공유 자원을 쥔 저우선순위 태스크의 우선순위를 대기 중인 고우선순위 수준으로 임시 상향시키는 프로토콜.
- **PCP(Priority Ceiling Protocol)**: 자원별로 접근 가능한 최고 우선순위를 사전 설정하여 교착상태와 우선순위 역전을 동시 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 뮤텍스 락 경합으로 인한 **우선순위 역전(Priority Inversion)** | **PIP(우선순위 상속)** 또는 **PCP(우선순위 천장)** 프로토콜 적용 | 고우선순위 태스크 블로킹 시간 최소화 및 기한 준수 |
| EDF 과부하 시 발생하는 연쇄 마감 실패 **도미노 현상** | CBS(Constant Bandwidth Server) 기반 CPU 대역폭 격리 | 비정상 태스크 격리 및 핵심 제어 태스크 보호 |
| 인터럽트 지연 및 OS 오버헤드로 인한 WCET 오차 | 타이밍 분석 시 OS 틱 지연 및 ISR 시간을 WCET에 마진 합산 | 스케줄 가능성 증명의 보수적 신뢰성 100% 확보 |
| 비주기적(Aperiodic) 긴급 이벤트 발생 시 처리 지연 | 산발 서버(Sporadic Server) 및 디퍼럴 서버(Deferrable Server) 배치 | 비주기적 이벤트의 무지연 즉시 응답 실현 |

#### 한줄 요약
- PIP/PCP 상속 프로토콜, CBS 대역폭 격리, WCET 안전 마진, Sporadic Server로 실무 신뢰성을 완성한다.

## Ⅶ. 결론

- 안전이 최우선인 하드 실시간 임베디드(AUTOSAR)는 **RM 알고리즘 및 PCP 프로토콜**을 적용하고, 자원 활용이 중요한 소프트 실시간은 **EDF 및 CBS**를 채택하여 결정론적 안전성 확립

#### 한줄 요약
- 실시간 스케줄링은 수학적 스케줄 가능성 증명과 우선순위 역전 방지 프로토콜의 결합을 통해 완성된다.
