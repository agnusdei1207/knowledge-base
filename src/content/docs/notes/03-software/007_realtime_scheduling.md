## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 스케줄링(Real-Time Scheduling)**: 계산 결과가 아무리 맞아도 0.1초라도 늦으면 시스템이 터지는 환경에서, 무조건 마감 시간 안에 끝내도록 멱살 잡는 강박증 스케줄링이다.
- **비율 단조(Rate Monotonic, RM)**: "자주 울리는 놈이 제일 급한 놈이다"라는 단순 무식한 철학으로, 주기가 제일 짧은 프로세스에게 최고 우선순위를 영원히 박아주는 정적 스케줄링이다.
- **최단 마감시간 우선(Earliest Deadline First, EDF)**: "발등에 불 떨어진 놈부터 살리자"는 철학으로, 마감 시간이 가장 코앞에 닥친 태스크에게 그때그때 동적으로 1빠따를 주는 스케줄링이다.
- **수용 제어(Admission Control)**: 새 태스크가 들어오려고 할 때 "너까지 받으면 다 같이 마감 시간 놓쳐서 폭망한다!"며 사전에 계산기 두드려보고 얄짤없이 컷(Cut)해버리는 문지기이다.

</details>

- 정의: 프로세스의 연산 결과뿐만 아니라 지정된 마감 시간(Deadline) 내 성공적 완료 여부로 생사가 갈리는 환경에서, 우선순위를 강박적으로 배분하는 **실시간 스케줄링 알고리즘**
- 배경: 일반적인 범용 OS의 처리량 위주 스케줄링(CFS 등)으로는 미사일 제어나 에어백 터뜨리기 같은 **마감시간 절대 준수 보장**이 아예 불가능하기 때문

#### 한줄 요약

- 일반 OS처럼 둥글게 사는 게 아니라, 제시간에 못 끝내면 죽는다는 각오로 순서를 멱살 잡고 통제하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 재수가 오지게 없어서 캐시 다 빗나가고 메모리 딜레이 떡칠된 상태로 코드를 돌렸을 때, 최악으로 걸리는 물리적인 최대 실행 시간이다.
- **스케줄 가능성 검증(Schedulability Test)**: 태스크들을 싹 다 돌렸을 때 마감을 단 하나라도 놓치는지 사전에 시뮬레이션 돌려보는 빡센 안정성 검사이다.

</details>

- 재수가 제일 없는 상황을 가정한 **최악 실행 시간(WCET)**과 주기, 마감 시간을 칼같이 분석해서 통제함.
- 주기가 짧을수록 벼슬을 주는 정적 마인드(**RM**)와 발등에 불 떨어진 놈을 구하는 동적 마인드(**EDF**)로 갈라짐.
- 시스템 터지는 걸 막으려고 런타임 전에 **스케줄 가능성 검증**을 빡세게 돌리고 **수용 제어**로 입구를 막아버림.

#### 한줄 요약

- 최악의 상황(WCET)을 가정한 뒤 마감을 못 맞출 것 같으면 애초에 놈을 받아주지 않는다(수용 제어).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이용률 상한선(Utilization Bound, U)**: "CPU를 이 비율까지만 써야 마감을 100% 지킬 수 있다"는 마지노선으로, RM은 69% 근처고 EDF는 100% 꽉 채워 쓸 수 있다.

</details>

```text
[ 실시간 스케줄링 십자포화 아키텍처 ]
      [ 실시간 태스크 모수 ]
   (WCET, 주기, 마감시간 제출)
                │
                ▼
      [ 스케줄 가능성 분석기 ]
(수용 제어 통과한 놈만 큐에 넣어줌)
                │
                ▼
       [ 우선순위 준비 큐 ]
(RM은 주기 짧은 순, EDF는 마감 급한 순)
                │
                ▼
        [ 선점 스케줄러 ]
     (하드웨어 타이머 강제 뺏기)
                │
                ▼
       [ CPU (실행 코어) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 실시간 태스크 모수 | 각 프로세스의 **최악 실행 시간(WCET)**, 언제마다 실행되는지(주기), 언제까지 끝내야 하는지(마감) 스펙 |
| 스케줄 가능성 분석기 | 놈들 다 합쳤을 때 **이용률 상한선(U)** 안 넘는지 계산기 두드려서 수용할지 거부할지 자르는 문지기 |
| 우선순위 준비 큐 | RM은 "자주 오는 놈", EDF는 "마감 코앞인 놈" 순서대로 멱살 잡고 줄 세워놓은 대기실 |
| 선점 스케줄러 | 큐 맨 앞에 더 급한 놈이 뜨면, 지금 도는 놈 멱살 잡고 강제로 끌어내리는 피도 눈물도 없는 심판 |

#### 한줄 요약

- 스펙(WCET)을 내면 분석기가 자르고, 통과한 놈들만 큐에 세워서 스케줄러가 멱살 잡고 CPU에 꽂는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 제일 짬 높은(고우선순위) 프로세스가 락(Mutex)을 쥔 짬찌(저우선순위)를 기다리다가, 중간 짬찌한테 새치기당해서 마감을 놓치고 폭망하는 현상이다.

</details>

```text
[ 실시간 스케줄링 반복 마감 십자포화 흐름 ]
  [ 1. 새 태스크 스펙(WCET, 주기) 제출 ]
                │
                ▼
    [ 2. 스케줄 가능성 계산 및 수용 판정 ]
                │
    ┌───────────┴───────────┐
 (고정 주기 기준)     (변동 마감 기준)
    ▼                       ▼
[ 3. RM 정렬 ]          [ 3. EDF 정렬 ]
(주기 짧으면 1빠)     (마감 급하면 1빠)
    └───────────┬───────────┘
                ▼
      [ 4. 무자비한 강제 선점 ]
                │
                ▼
   [ 5. 마감 준수 감시 및 과부하 통제 ]
                └─── (다음 릴리스로 반복)
```

### 동작 원리

1. 수용 판정: 태스크가 들어오면 WCET랑 주기 들이밀고 **이용률(U)** 계산해서 통과할지 말지 입구 컷 쳐냄.
2. 정책 선택: 묻지도 따지지도 않고 주기 짧은 게 왕이면 **RM**, 마감 급한 게 왕이면 **EDF**를 탐.
3. 큐 정렬: 뽑은 정책에 따라 준비 큐를 칼같이 줄 세움.
4. 선점 디스패치: 지금 실행 중인 놈보다 더 급한 놈이 발생하면, 가차 없이 기존 놈 멱살 잡고 내쫓음.
5. 마감 감시: 미친 듯이 감시하다가 부하가 걸리면 안 중요한 놈부터 가차 없이 죽여버려서 마감을 사수함.

#### 한줄 요약

- 입구 컷 치고, 정책 골라서 줄 세우고, 더 급한 놈 오면 무자비하게 뺏으면서 마감을 지킨다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도미노 효과(Domino Effect)**: EDF 환경에서 하나가 마감 시간 넘겨서 자원을 계속 물고 늘어지면, 뒤에 줄 서 있던 놈들도 줄줄이 마감 놓치고 터지는 대형 참사이다.

</details>

| 비교 항목 | **RM** (Rate Monotonic) | **EDF** (Earliest Deadline First) |
|:---|:---|:---|
| 우선순위 할당 방식 | **정적** (주기가 짧을수록 태어날 때부터 금수저 계급 박아줌) | **동적** (지금 당장 발등에 불 떨어진 놈이 임시 왕 먹음) |
| CPU 뽕뽑기(이용률 상한) | 약 **69%** 넘어가면 마감 터질 수 있어서 강제로 놀려야 함 | 꽉꽉 채워서 **100%** 돌려도 마감 사수 가능함 |
| 런타임 오버헤드 체감 | 우선순위가 안 변하니까 큐 관리 오버헤드가 거의 없음 | 켜질 때마다 누가 급한지 다시 계산해야 해서 딜레이 큼 |
| 과부하 터졌을 때 동작 | 낮은 계급(주기 긴 놈)부터 순서대로 포기해서 예측하기 쉬움 | 누가 죽을지 모르고 뒤에 놈들까지 줄줄이 터지는 **도미노 현상** 발생 |

#### 한줄 요약

- 맘 편하게 예측하려면 정적인 RM을 쓰고, 딜레이 감수하고 CPU 100% 쥐어짜려면 동적인 EDF를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **피아이피(Priority Inheritance Protocol, PIP)**: 우선순위 역전을 막기 위해, 락을 쥐고 있는 짬찌의 우선순위를 락 대기 중인 최고참 등급으로 잠깐 강제 뻥튀기시켜주는 꼼수이다.
- **피씨피(Priority Ceiling Protocol, PCP)**: 자원 자체에 락 상한선을 박아버려서 우선순위 역전은 물론 데드락까지 원천 차단하는 가장 빡센 통제법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중간 놈이 새치기해서 높은 놈이 뻗어버리는 **우선순위 역전** 발생 | **피아이피(PIP)**나 **피씨피(PCP)** 프로토콜을 멱살 잡고 강제 적용함 | 짬찌가 락을 쥐고 버티는 시간을 최소화하고 데드락까지 100% 방어 |
| EDF 쓰는데 과부하 걸려서 마감 놓치면 **도미노 효과**로 다 같이 동반 자살함 | **수용 제어** 입구 컷을 빡세게 잡고 덜 중요한 태스크는 쿨하게 버림 | 핵심 태스크의 시스템 생존력(Survival)을 최우선으로 사수 |
| 락 걸리고 인터럽트 터지면서 **최악 실행 시간(WCET)** 계산이 다 꼬여버림 | 운영체제 오버헤드를 아예 $C_i$ 보정치에 때려 박아서 보수적으로 계산함 | 스케줄 가능성 분석이 빗나가서 시스템이 터지는 억까 차단 |

#### 한줄 요약

- 우선순위 역전은 PIP/PCP로 뚫고, EDF 도미노 폭발은 중요도 낮은 놈을 내버려서 생존을 사수해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실시간 스케줄링 선택 기준(Real-Time Scheduling Selection Criteria)**: 프로세스가 예측 가능한 주기로 뛰는지, CPU를 끝까지 쥐어짜야 하는지 따져서 미사일 제어기 설계를 결정하는 잣대이다.

</details>

- **실시간 스케줄링 선택 기준** 원칙에 따라, 웬만하면 과부하 때 예측 가능한 **RM**을 박아놓고, 자원 100% 쥐어짜야 할 때만 **EDF** 채택 기조 확립함

#### 한줄 요약

- 미사일 제어기처럼 터지면 다 죽는 환경에선 예측 가능한 RM을 우선으로 도입한다.
