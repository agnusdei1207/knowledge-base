## 미리 알고가기

- **일관성 C(씨, Consistency)**: 일관성의 영어 첫 글자를 써서 모든 노드가 같은 최신값을 제공해야 함을 나타내며 CAP의 선택 기준임
- **가용성 A(에이, Availability)**: 가용성의 영어 첫 글자를 써서 모든 요청에 실패 아닌 응답을 제공해야 함을 나타내며 CAP의 선택 기준임
- **분할 허용성 P(피, Partition Tolerance)**: 분할 허용성의 영어 첫 글자를 써서 통신 단절에도 시스템을 운영해야 함을 나타내며 CAP의 전제임
- **CP(씨피, Consistency and Partition Tolerance)**: C와 P를 붙여 분할 중 일관성을 우선한다는 조합을 나타내며 CAP 비교의 한 선택지임
- **AP(에이피, Availability and Partition Tolerance)**: A와 P를 붙여 분할 중 가용성을 우선한다는 조합을 나타내며 CAP 비교의 한 선택지임
- **CAP 정리(캡, Consistency, Availability, Partition Tolerance Theorem)**: 세 영어 핵심어의 첫 글자를 붙여 네트워크 분할 중 일관성과 가용성을 동시에 완전히 보장할 수 없음을 나타내며 분산 정책 선택의 기준임
- **PACELC 정리(파셀크, Partition: Availability/Consistency, Else: Latency/Consistency)**: 분할 시 P와 A/C, 정상 시 Else와 L/C를 나눠 적어 두 상태의 절충을 나타내며 CAP를 확장한 판단 틀임
- **DB(Database)**: ‘디비’로 읽고 영문 머리글자를 딴 약어이며, 데이터를 구조화해 저장·관리하는 시스템임
- **네트워크 분할(Network Partition)**: 노드 일부가 서로 통신하지 못해 독립된 집단처럼 동작하는 장애임
- **정족수(Quorum)**: 분산 읽기나 쓰기를 확정하기 위해 필요한 최소 노드 응답 수임
- **충돌 해결(Conflict Resolution)**: 서로 다른 사본의 변경을 규칙에 따라 하나의 상태로 합치는 처리임
- **수렴(Convergence)**: 통신 복구와 동기화 뒤 모든 사본이 같은 상태에 도달하는 성질임

## Ⅰ. 개요

- 정의/개념: 분할 중 **일관성·가용성 절충**을 설명하는 정리
- 기존 한계: 통신 단절 시 **최신값·응답 동시 보장** 불가

### 쉽게 이해하기 (학습용)
- 전화가 끊겼을 때 영업을 멈출지 임시 기록으로 영업할지 정하는 문제임

## Ⅱ. 특징

- **분할 장애 상황**에서 C와 A의 선택을 설명
- **CP**는 최신 상태를 위해 일부 요청 지연·거절
- **AP**는 응답을 위해 일시적 불일치 허용

### 쉽게 이해하기 (학습용)
- 분할은 피할 수 없으므로 정확성과 응답 중 무엇을 지킬지 선택해야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 복제 노드 | 같은 데이터의 사본을 분산 보관함 |
| 분할 감지 | 노드 간 통신 단절을 판정함 |
| 일관성 정책 | 최신값 확인 범위와 차단 조건을 정함 |
| 가용성 정책 | 분할 중 계속 처리할 요청을 정함 |

```text
  분할감지
      ↓
  정책선택
      ↓
  요청통제
      ↓
  사본복구
```

> 요약: 분할 감지와 일관성 및 가용성 정책으로 처리를 결정함

### 쉽게 이해하기 (학습용)
- 단절 시 일관성은 최신값을 지키고 가용성은 응답 지속을 지킴

## Ⅳ. 원리 및 절차 흐름도

```text
  사본운영
      ↓
  분할감지
      ↓
  정책적용
      ↓
  충돌해결
```

| 절차 | 설명 |
|:---|:---|
| 복제운영 | 순서와 버전 규칙으로 사본을 유지함 |
| 장애감지 | 통신 단절과 정족수 상태를 감지함 |
| 정책적용 | 일관성은 제한하고 가용성은 계속 처리함 |
| 복구확인 | 충돌을 해결하고 사본 수렴을 확인함 |

> 요약: 분할 중 일관성은 제한하고 가용성은 처리한 뒤 수렴함

### 쉽게 이해하기 (학습용)
- 분할 중 CP는 최신 상태를 확인할 수 없는 요청을 거부하고 AP는 각 사본에서 처리한 뒤 복구 시 충돌을 해결함

## Ⅴ. 종류 및 비교

| CAP 정책 | CP | AP |
|:---|:---|:---|
| 적용 기준 | 거래·재고의 **최신값 우선** | 피드·추천의 **응답 우선** |
| 핵심 특징 | 확인 불가 요청 **지연·거절** | 처리 지속 후 **사본 수렴** |
| 한계 | 분할 중 **가용성 저하** | 일시 불일치·**병합 충돌** |

> 요약: 일관성은 상태를 지키고 가용성은 분할 중 응답을 우선함

### 쉽게 이해하기 (학습용)
- 일관성은 거래를 멈추고 가용성은 임시 차이를 허용함

## Ⅵ. 실무 사례

1. 재고 분할 시 **CP로 쓰기 제한**
2. 피드 분할 시 **AP로 응답 유지**

### 쉽게 이해하기 (학습용)
- 재고 차감은 중복 판매를 피하려고 최신 상태를 확인할 수 없는 쓰기를 거부하는 CP 정책을 적용할 수 있음
- 피드 조회는 잠시 오래된 결과를 허용하고 계속 응답한 뒤 복구 시 사본을 맞추는 AP 정책을 적용할 수 있음

## Ⅶ. 결론

- 최신값 우선은 **CP**, 응답 우선은 **AP**

### 쉽게 이해하기 (학습용)
- CAP는 분할 장애의 선택을 설명하고 PACELC는 정상 상태의 지연·일관성 절충까지 확장하므로 두 상황을 따로 검증해야 함
