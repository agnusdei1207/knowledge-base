## 미리 알고가기

- **개체 무결성 (Entity Integrity)**: 기본키의 유일성과 필수값을 보장함
- **참조 무결성 (Referential Integrity)**: 외래키의 부모 관계를 보장함
- **기본키 (Primary Key, PK)**: 각 행을 유일하게 식별함
- **외래키 (Foreign Key, FK)**: 부모 테이블의 후보키를 참조함
- **참조 동작 (Referential Action)**: 부모 변경 시 자식 처리 방식을 정함
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **후보키(Candidate Key)**: 행을 유일하게 식별하는 최소 속성 집합임
- **널(Null)**: 값이 없거나 알려지지 않았음을 나타내는 특별한 상태임
- **고아 데이터(Orphan Data)**: 외래키가 가리킬 부모 행이 없어 관계가 끊긴 자식 데이터임
- **제한(Restrict)**: 참조하는 자식 행이 있으면 부모의 삭제·변경을 거부하는 동작임
- **연쇄(Cascade)**: 부모 키의 삭제·변경을 관련 자식 행에도 자동 적용하는 동작임
- **널 설정(Set Null)**: 부모가 삭제·변경될 때 허용된 자식 외래키를 널로 바꾸는 동작임
- **데이터 이관(Data Migration)**: 데이터를 다른 시스템이나 구조로 옮기는 작업임

## Ⅰ. 개요

- **정의/개념**: 행 식별과 부모·자식 관계를 보장함
- **배경/필요성**: 중복 키·고아 행 발생으로 무결성 제약 필요

### 쉽게 이해하기 (학습용)
- 겹치지 않는 번호를 주고 실제 존재하는 사람만 적게 하는 규칙임

## Ⅱ. 특징

- 개체 무결성은 중복 행과 식별 불가 상태를 방지한다.
- 참조 무결성은 부모와 자식의 연결 단절을 방지한다.
- 삭제·갱신 정책이 데이터 안전성과 운영 편의를 좌우한다.
- 위반 데이터는 조회·집계·업무 판단의 신뢰성을 낮춘다.

### 쉽게 이해하기 (학습용)
- 이름표가 겹치거나 고아 기록이 생기면 자료를 믿을 수 없게 됨

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 기본키 | 각 행을 유일하게 식별함 |
| 외래키 | 자식 행을 부모 후보키와 연결함 |
| 참조 동작 | 부모 변경 시 자식 처리 방식을 정함 |
| 검증 절차 | 중복 키와 고아 데이터를 검사함 |

```text
  기본식별
      ↓
  참조연결
      ↓
  동작지정
      ↓
  정합검증
```

> 요약: 기본키와 외래키 및 참조 동작으로 관계를 유지함

### 쉽게 이해하기 (학습용)
- 기본키로 행을 식별하고 외래키로 부모와 자식을 연결함

## Ⅳ. 원리 및 절차 흐름도

```text
  관계식별
      ↓
  기본설정
      ↓
  참조연결
      ↓
  동작검증
```

| 절차 | 설명 |
|:---|:---|
| 관계식별 | 독립 개체와 부모 및 자식 관계를 구분함 |
| 기본키설정 | 후보키 중 기본키를 정해 중복을 금지함 |
| 외래키연결 | 외래키를 부모 후보키에 연결함 |
| 동작검증 | 삭제와 갱신 시 참조 동작을 검증함 |

> 요약: 기본키를 정하고 외래키와 참조 동작을 검증함

### 쉽게 이해하기 (학습용)
- 기본키와 외래키를 연결하고 부모 변경 동작을 검증함

## Ⅴ. 종류 및 비교

| 비교축 | 개체 무결성 | 참조 무결성 |
|:---|:---|:---|
| 핵심 특징 | 한 테이블의 행 식별을 통제함 | 부모와 자식 관계를 통제함 |
| 핵심 규칙 | 기본키의 중복과 누락을 금지함 | 존재하는 부모를 참조함 |
| 적용 기준 | 행의 유일한 식별이 필요할 때 적용함 | 테이블 간 참조 유지가 필요할 때 적용함 |
| 주요 위험 | 중복·NULL 기본키 | 고아 참조·삭제 연쇄 |

> 요약: 개체는 행, 참조는 부모·자식 관계 보장

### 쉽게 이해하기 (학습용)
- 개체 무결성은 행을 지키고 참조 무결성은 관계를 지킴

## Ⅵ. 실무 사례

1. 주문 시스템은 삭제 정책과 고아 데이터를 확인함
2. 데이터 이관은 외래키와 고아 데이터를 검증함

### 쉽게 이해하기 (학습용)
- 주문 시스템은 고객 삭제 시 제한·연쇄·널 설정 중 업무 의미에 맞는 동작을 정해 고아 주문을 방지함
- 데이터 이관 뒤 외래키 검사를 실행하면 누락된 부모와 잘못 연결된 자식 데이터를 운영 전에 찾을 수 있음

## Ⅶ. 결론

- 기본키와 외래키로 행과 관계의 신뢰성 확보

### 쉽게 이해하기 (학습용)
- 개체 무결성은 행의 정체성을, 참조 무결성은 관계의 유효성을 지키며 삭제 정책까지 업무 의미에 맞아야 함
