## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **클라우드 4대 배포 모델**: 공용 자원을 임대하는 퍼블릭(Public), 전용 IDC를 독점하는 프라이빗(Private), 온프레미스와 퍼블릭을 연계하는 하이브리드(Hybrid), 복수의 CSP를 병용하는 멀티 클라우드(Multi-Cloud).
- **보안 컴플라이언스 및 인프라 비용 한계(Compliance & Cost Tradeoff)**: 금융/공공 규제로 인한 전면 퍼블릭 전환 불가와 온프레미스 자원의 물리적 증설 한계가 충돌하는 위험.

</details>

- 정의/개념: 인프라의 위치와 점유 독점성 및 연결 방식에 따라 **퍼블릭, 프라이빗, 하이브리드, 멀티 클라우드로 분류한 배포 아키텍처** 모델
- 배경/필요성: 온프레미스 자원의 증설 한계와 퍼블릭 클라우드의 규제 준수 제약 사이에서 발생하는 **보안 컴플라이언스 및 인프라 비용 최적화 한계** 직면

#### 한줄 요약

- 보안 규제, 탄력성, 가용성 요구사항에 따라 4대 배포 모델을 적재적소에 조합하여 최적의 인프라 거버넌스를 구현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클라우드 버스팅(Cloud Bursting)**: 평시에는 프라이빗 클라우드를 사용하다가 트래픽 폭증 시 퍼블릭 클라우드로 연산 자원을 자동 확장(Burst)하는 기법.
- **데이터 아웃바운드 비용(Egress Fee)**: 서로 다른 클라우드 또는 온프레미스로 데이터를 전송할 때 발생하는 네트워크 통신 과금.

</details>

- 멀티테넌시 기반 탄력적 확장을 제공하는 **퍼블릭 클라우드의 비용 효율성**
- 단일 조직 전용 인프라로 완전한 보안 통제를 보장하는 **프라이빗 클라우드의 규제 준수**
- 전용선(Direct Connect) 기반 연계를 통한 **하이브리드 및 멀티 클라우드의 유연성** #### 한줄 요약

- 퍼블릭의 민첩성과 프라이빗의 통제력을 결합하여 벤더 종속성을 방지하고 고가용성을 확보

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **전용선 및 통합 IAM 연계**: On-Premise와 Public Cloud를 연결하는 Direct Connect/VPN과 전사 접근 제어를 단일화하는 통합 IAM(IdP).

</details>

```text
[ 클라우드 4대 배포 모델 및 하이브리드 연계 구조도 ]

 1. [ 온프레미스 프라이빗 클라우드 (Private IDC) ]
    - 민감 금융/개인정보 원장 DB, 폐쇄망 레거시 시스템
                            │
                            │ (AWS Direct Connect / VPN 전용선)
                            ▼
 2. [ 퍼블릭 클라우드 1 (AWS Public Cloud) ]
    - 대외 고객 서비스 웹/앱, 오토스케일링 API Gateway
                            │
                            │ (Multi-Cloud 상호 연동 / OIDC)
                            ▼
 3. [ 퍼블릭 클라우드 2 (GCP / Azure Cloud) ]
    - 빅데이터 AI/ML 학습 (BigQuery / Vertex AI)
```

선의 의미: 프라이빗 인프라와 복수의 퍼블릭 클라우드가 전용선과 통합 네트워크로 연결된 하이브리드·멀티 클라우드 구조.

| 구성요소 | 책임 |
|:---|:---|
| 퍼블릭 클라우드 (Public) | 글로벌 CSP의 공유 인프라를 활용하여 **대규모 트래픽 탄력적 오토스케일링 제공** |
| 프라이빗 클라우드 (Private) | 기업 전용 데이터센터를 구축하여 **핵심 원장 데이터의 완전한 주권 및 보안 통제** |
| 하이브리드 연계 (Hybrid) | 전용선 및 VPN을 구축하여 **프라이빗과 퍼블릭 간의 데이터 동기화 및 버스팅 조율** |
| 멀티 클라우드 관리 (Multi) | 2개 이상의 CSP 자원을 통합 관리하여 **벤더 락인을 방지하고 재해복구(DR) 다중화** |

#### 한줄 요약

- 퍼블릭, 프라이빗, 하이브리드 연계망, 멀티 클라우드 관리가 유기적으로 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **클라우드 배포 모델 선정 5단계 절차**: 데이터 분류 $\to$ 탄력성 평가 $\to$ 모델 선정 $\to$ 전용선/IAM 설계 $\to$ 비용 및 DR 검증.

</details>

```text
[ 비즈니스 워크로드 배포 모델 결정 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 데이터 민감도 및 국가 규제 준수 분류│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 트래픽 변동성 및 지연시간(Latency) 평가│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 최적 배포 모델(Public/Private/Hybrid) 선정
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 전용선(Direct Connect) 및 통합 IAM 설계│
 └───────────────────┬────────────────────┘
                     │

 ┌────────────────────────────────────────┐
 │ 5. Egress 네트워크 비용 및 DR 복구 검증│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 데이터 분류: 개인정보, 금융 계좌 등 법적 규제 대상 데이터와 일반 대외 서비스 데이터를 식별.
2. 탄력성 평가: 이벤트 시 수십 배 이상 트래픽이 폭증하는지, 고정적인 워크로드인지 분석.
3. 모델 선정: 코어 원장은 프라이빗에, 대외 웹 서비스는 퍼블릭에 배치하는 하이브리드/멀티 전략 수립.
4. 연계망 설계: Direct Connect 전용선과 HashiCorp Vault 기반 통합 인증(IAM)을 구성.
5. 비용 검증: 데이터 이동 시 발생하는 Egress 네트워크 비용과 리전 장애 시 DR 페일오버 경로를 검증.

#### 한줄 요약

- 데이터 분류 $\to$ 탄력성 평가 $\to$ 모델 선정 $\to$ 연계망 설계 $\to$ 비용/DR 검증의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **4대 배포 모델 비교**: Public(탄력성), Private(보안 통제), Hybrid(유연한 절충), Multi-Cloud(DR 및 벤더 독립).

</details>

| 구분 | 퍼블릭 클라우드 (Public) | 프라이빗 클라우드 (Private) | 하이브리드/멀티 클라우드 (Hybrid/Multi) |
|:---|:---|:---|:---|
| **적용 기준** | 대외 웹 서비스, 모바일 앱, 스타트업 | 금융 코어 뱅킹, 국방, 엄격한 망분리 규제 | 레거시 연계 엔터프라이즈 및 글로벌 서비스 |
| **핵심 특징** | **멀티테넌시 공유 자원, 종량제(OpEx), 무한 확장** | **단일 조직 독점 자원, 자본투자(CapEx), 완전 통제** | **온프레미스+퍼블릭 결합, 벤더 종속 방지, 고가용 DR** |
| **한계** | 데이터 상주 규제 제약 및 장기 비용 증가 | 초기 막대한 인프라 구축비 및 확장 유연성 부족 | 네트워크 이종망 관리 복잡도 및 Egress 비용 발생 |

#### 한줄 요약

- 빠른 확장은 퍼블릭, 강력한 통제는 프라이빗, 규제와 탄력성을 절충할 때는 하이브리드/멀티를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Egress 비용 및 통합 보안 거버넌스**: 클라우드 간 데이터 전송 비용을 최소화하고 서로 다른 CSP의 보안 정책을 일원화하는 실무 대응 방안.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이종 클라우드 간 대용량 데이터 전송 시 Egress 비용 폭증 | **데이터 상주 영역 최적화 및 Dedicated Direct Connect 구축** | 네트워크 전송 비용 50% 이상 절감 |
| 클라우드별 IAM 정책 상이로 인한 보안 관리 복잡성 | **OIDC 기반 중앙 Identity Provider 및 HashiCorp Vault 연동** | 단일 창구 기반 통합 접근 통제 |
| 프라이빗 클라우드 피크 타임 용량 고갈로 인한 서비스 마비 | **K8s 기반 클라우드 버스팅(Cloud Bursting) 자동화 파이프라인 구성** | 피크 트래픽 다운타임 방지 |

#### 한줄 요약

- Egress 비용 최적화, 통합 IAM 구축, 클라우드 버스팅 자동화를 통해 하이브리드 인프라를 안정화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **하이브리드 네이티브(Hybrid-Native Infrastructure)**: 온프레미스와 다중 클라우드를 단일 가상 인프라처럼 운영하는 쿠버네티스 기반 현대적 플랫폼.

</details>

- **클라우드 배포 모델** 엔터프라이즈 인프라 설계의 핵심 전략이며, 데이터 주권과 비즈니스 탄력성을 종합 고려하여 프라이빗의 안정성과 퍼블릭의 확장성을 결합한 하이브리드·멀티 클라우드 아키텍처를 구축해야 함

#### 한줄 요약

- 4대 배포 모델의 장점을 융합하여 보안 규제 준수와 비즈니스 민첩성을 동시에 완성
