## 미리 알고가기

- **퍼블릭 클라우드**: 공급자 소유 자원을 여러 소비자에게 서비스 형태로 제공한다
- **프라이빗 클라우드**: 한 조직만 사용하는 클라우드 자원과 관리 체계를 구성한다
- **하이브리드 클라우드**: 프라이빗 환경과 퍼블릭 클라우드를 연결해 업무를 배치한다
- **멀티 클라우드**: 퍼블릭·프라이빗·하이브리드 같은 소유 형태가 아니라 둘 이상의 퍼블릭 공급자를 업무별로 병행하는 운영 구성이다
- **워크로드 배치**: 데이터 위치·규제·지연·서비스 종속성을 기준으로 실행 환경을 정하는 활동이다
- **리전**: 클라우드 공급자가 여러 데이터 센터를 묶어 서비스를 제공하는 지역 단위이다
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: ‘에이피아이’로 읽고 영문 머리글자를 딴 표기이며 다른 서비스 기능을 호출하는 규약이다
- **공통 신원(Common Identity, Common ID)**: ‘커먼 아이디’로 읽고 Identity를 ID로 줄인 표기이며 여러 환경의 사용자 신원·권한을 연결한다
- **데이터 복제·동기화**: 데이터를 다른 환경에 복사하고 변경 내용을 일치시키는 방식이다
- **통합 관측**: 여러 환경의 지표·로그·추적 정보를 한 기준으로 수집해 상태를 판단하는 활동이다
- **공급자 종속**: 특정 공급자의 기능과 형식에 의존해 다른 환경으로 이전하기 어려운 상태이다

## Ⅰ. 개요

- **정의/개념**: 자원 소유권과 접근 범위로 환경을 구분한다
- **배경/필요성**: 업무별 규제·비용이 달라 실행 위치 결정 필요

### 쉽게 이해하기 (학습용)
- 클라우드를 어디에 만들고 업무를 어디 둘지 정한다

## Ⅱ. 특징

- 자원 소유권과 접근 주체로 배포 모델을 구분한다.
- 환경 결합에는 네트워크·신원·관측 통합이 필요하다.
- 규제·비용·서비스 요구로 워크로드 위치를 정한다.
- 환경이 늘면 장애 분리는 쉬워지나 운영 중복이 커진다.

### 쉽게 이해하기 (학습용)
- 실행 환경을 늘리면 연결 설계와 비용 관리 인력이 늘어난다

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 역할 |
|:---|:---|
| 워크로드·실행 환경 | 등급과 지연 정보로 각 환경의 배치 후보를 정함 |
| 연결 계층 | 경로 설정을 통해 환경 간 통신 통로를 구성함 |
| 공통 ID·정책 | 계정 연동과 권한·구성 기준을 환경마다 적용함 |
| 데이터 이동 계층 | 복제와 동기화 경로 및 데이터 위치를 관리함 |
| 통합 관측·비용 | 환경별 지표와 비용을 공통 기준으로 수집함 |

```text
  업무분류
      ↓
  환경선정
      ↓
  경계설계
      ↓
  정책적용
      ↓
  배치조정
```

> 요약: 여러 실행 환경의 정책과 관측은 공통 계층에서 통제한다

### 쉽게 이해하기 (학습용)
- 실행 장소가 달라도 보안 규칙은 같은 기준으로 확인한다

## Ⅳ. 원리 및 절차 흐름도

```text
업무분류
   ↓
환경선정
   ↓
경계설계
   ↓
정책적용
   ↓
배치조정
```

| 절차 | 설명 |
|:---|:---|
| **업무분류** | 데이터 등급과 가용성 요구를 분류함 |
| **환경선정** | 비용 대비 적합한 클라우드 후보를 선정함 |
| **경계설계** | 환경 간 네트워크와 데이터 경로를 설계함 |
| **정책적용** | 계정과 보안 기준을 전 환경에 적용함 |
| **배치조정** | 성능과 가동률을 확인해 업무 배치를 조정함 |

> 요약: 업무 조건으로 실행 환경을 정하고 배치 적합성을 검증한다

### 쉽게 이해하기 (학습용)
- 업무 조건에 맞는 환경을 결정하고 공통 관측 체계를 연결한다

## Ⅴ. 종류 및 비교

| 비교축 | 퍼블릭 | 프라이빗 | 하이브리드 | 멀티 클라우드 |
|:---|:---|:---|:---|:---|
| 핵심 특징 | 공급자 자원을 공용 사용함 | 한 조직 전용 자원을 사용함 | 전용과 공용 자원을 결합함 | 여러 공용 공급자 자원을 씀 |
| 업무 배치 | 공급자 리전에 배치함 | 전용 환경에 배치함 | 업무와 데이터를 두 환경에 나눔 | 업무를 공급자별로 나눠 배치함 |
| 운영 의존성 | 단일 공급자 API에 의존함 | 조직이 플랫폼 수명주기를 담당함 | 연결과 동기화 도구에 의존함 | 공급자별 API 차이 비용 발생함 |
| 적용 기준 | 확장성과 유연한 자원 필요 시 | 높은 보안 수준과 독점 통제 필요 시 | 보안은 내부, 부하는 외부에 둘 때 | 특정 공급자 종속을 피하고자 할 때 |
| 주요 위험 | 공급자 종속·비용 변동 | 용량·운영 인력 증가 | 연결·정합성 복잡도 | 정책·기술 분산 |

> 요약: 소유와 배치 범위 및 운영 의존성으로 모델을 구분한다

### 쉽게 이해하기 (학습용)
- 퍼블릭·프라이빗은 접근 범위를, 하이브리드·멀티는 환경 조합을 구분한다

## Ⅵ. 실무 사례

1. 개인정보는 내부에 두고 API는 공용에 배치한다
2. 분석은 특화 서비스를 사용하고 월 비용을 확인한다

### 쉽게 이해하기 (학습용)
- 하이브리드는 개인정보 위치와 환경 간 API 연결을 함께 검증한다
- 멀티 클라우드는 분석 성능과 공급자별 월 비용을 함께 비교한다

## Ⅶ. 결론

- 통제 범위·연결 비용·종속성으로 모델을 결정한다

### 쉽게 이해하기 (학습용)
- 데이터 위치와 환경 간 연결 비용이 요구에 맞는 모델을 선택한다
