## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **로보틱 프로세스 자동화(Robotic Process Automation, RPA)**: 사람이 컴퓨터 화면을 통해 수행하는 반복적이고 규칙 기반적인 정형 업무를 소프트웨어 봇이 사람의 행동 양식 그대로 모방하여 자동 실행하는 기술 체계이다.
- **소프트웨어 봇(Software Bot)**: 사람을 대신하여 사용자 화면, 파일, 시스템 API 등을 조작하고, 사전에 정의된 논리적 순서(스크립트)에 따라 업무를 완수하는 독립적인 가상 워커(Virtual Worker) 프로그램이다.

</details>

- 정의/개념: 기존 레거시 시스템의 변경 없이 **소프트웨어 봇(Software Bot)**을 활용하여 규칙 기반의 화면 조작 업무를 신속하게 자동화하는 **로보틱 프로세스 자동화(Robotic Process Automation, RPA)** 체계이다.
- 배경/필요성: 수작업에 의존하는 단순 반복적인 데이터 입력 작업은 업무 처리 지연, 휴먼 에러 발생, 불필요한 인건비 증가를 초래하여 비즈니스 생산성을 저하시키기 때문에 도입이 요구된다.

#### 한줄 요약
- 인간이 매일 같은 화면을 열고 데이터를 옮겨 적는 기계적인 행동 패턴을 가상 워커가 대신 수행하고, 예외 상황만 사람에게 에스컬레이션하는 지능형 업무 자동화 체계

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **작업 큐(Work Queue)**: 다수의 소프트웨어 봇이 병렬로 처리해야 할 업무 트랜잭션 아이템과 그 처리 상태(대기, 진행, 성공, 실패)를 순차적으로 보관하고 분배하는 중앙 대기열이다.
- **사용자 인터페이스(User Interface, UI)**: 사람이 업무 시스템에 데이터를 입력하거나 조회할 수 있도록 제공되는 시각적 화면 접점으로, RPA가 시스템과 상호작용하는 주된 통로이다.
- **프로세스 마이닝(Process Mining)**: 기업 내 다양한 시스템의 이벤트 로그를 분석하여 실제 업무 흐름을 시각화하고, 병목 구간과 과도한 반복 작업을 찾아내어 최우선 자동화 후보를 발굴하는 데이터 기반 분석 기법이다.
- **오케스트레이터(Orchestrator)**: 다수의 소프트웨어 봇에 대한 배포, 스케줄링, 작업 큐 할당, 보안 자격증명 관리 및 실행 로그 모니터링을 중앙에서 총괄 지휘하는 관제 서버 시스템이다.

</details>

- 기존 레거시 시스템의 백엔드를 수정하지 않고 **사용자 인터페이스(User Interface, UI)** 레이어를 직접 활용하므로 자동화 도입 속도가 매우 빠르다.
- **오케스트레이터(Orchestrator)** 중심의 아키텍처와 **작업 큐(Work Queue)**를 통해 수많은 봇의 업무 할당과 보안 자격증명을 중앙에서 안전하게 통제한다.
- 단순히 사람의 감에 의존하지 않고 **프로세스 마이닝(Process Mining)** 기법을 접목하여 가장 ROI가 높은 표준 반복 업무 후보를 과학적으로 발굴한다.

#### 한줄 요약
- 레거시 시스템을 뜯어고치지 않는 비침투적 방식으로 기존 화면을 그대로 활용하되, 실행 통제는 오케스트레이터 중심의 중앙 집중형으로 관리하는 유연한 아키텍처

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 불안정한 화면(UI) 조작 대신, 백엔드 시스템과 직접 통신하여 기능과 데이터를 호출하고 응답받기 위해 명확히 정의된 소프트웨어 간의 통신 계약이다.
- **업무 담당자(Human Operator)**: 봇이 처리할 수 없는 예외 상황(Business Exception)이나 화면 변경으로 인한 오류 발생 시, 이를 수동으로 판단·승인하고 자동화 룰을 보완하는 인간 작업자(Human-in-the-loop)이다.

</details>

```text
RPA 운영 구조
      |
      +-- [오케스트레이터]
      |
      +-- [소프트웨어 봇]
                +-- [업무 시스템 UI]
                +-- [업무 시스템 API]
                +-- [업무 담당자]
```

| 구성요소 | 책임 |
|:---|:---|
| **오케스트레이터(Orchestrator)** | 다수 봇의 스케줄링, 작업 큐 분배, 라이선스 관리, 권한 및 로그 중앙 통제 수행 |
| **소프트웨어 봇(Software Bot)** | 정의된 스크립트 규칙에 따라 실제 애플리케이션의 화면, 파일, API를 기계적으로 조작 |
| **사용자 인터페이스(User Interface, UI)** | 기존 애플리케이션의 화면 요소(버튼, 텍스트박스 등)를 통한 데이터 입력 및 조회 |
| **응용 프로그래밍 인터페이스(API)** | 화면 변경에 영향을 받지 않는 안정적인 백엔드 통신 계약으로 고속 데이터 연동 지원 |
| **업무 담당자(Human Operator)** | RPA가 처리 불가능한 예외 케이스의 수동 처리, 최종 승인 및 지속적 규칙 보완 담당 |

#### 한줄 요약
- 중앙 관제탑(오케스트레이터)이 가상 워커(봇)에게 작업 지시와 권한을 부여하고, 봇은 UI와 API를 통해 시스템과 통신하며 막힌 업무는 인간 담당자에게 이관하는 협업 구조

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 작업•자격증명 전달(Task•Credential Delivery)**: 중앙의 오케스트레이터가 작업 큐에 쌓인 개별 아이템과 해당 작업 수행에 필요한 최소 권한의 암호화된 자격증명을 유휴 봇에 안전하게 할당하는 단계이다.
- **2. 업무 입력•조회(Business Input•Inquiry)**: 소프트웨어 봇이 할당받은 업무 스크립트를 바탕으로 레거시 UI 또는 백엔드 API를 통해 정해진 업무 프로세스를 자동 실행하는 단계이다.
- **3. 완료•증적 기록(Completion•Evidence Recording)**: 트랜잭션이 성공적으로 처리되면 최종 결과, 화면 캡처, 시스템 로그 등을 투명한 감사(Audit)가 가능하도록 오케스트레이터 데이터베이스에 이력으로 보존하는 단계이다.
- **4. 예외•증적 이관(Exception•Evidence Transfer)**: 사전에 정의된 규칙을 벗어나는 예외(비즈니스 예외)나 화면 변경에 따른 오류(시스템 예외) 발생 시, 실행을 즉각 중단하고 관련 증적을 업무 예외함으로 이관하여 사람에게 넘기는 단계이다.

</details>

```text
1. 작업•자격증명 전달
      |
      v
2. 업무 입력•조회
      |
      +-- 스크립트 규칙 내 정상 결과 도출
      |         |
      |         v
      |   3. 완료•증적 기록
      |
      +-- 룰 위반 및 시스템 예외 발생
                |
                v
          4. 예외•증적 이관
                |
                +-- 인간 담당자의 비즈니스 판단 및 예외 승인
                +-- 원인 분석 및 스크립트 규칙 보완 후 작업 재처리
```

### 동작 원리

1. **작업•자격증명 전달(Task•Credential Delivery)**: 봇 풀(Bot Pool)의 가용 봇에 작업 아이템과 보안 크레덴셜을 매핑한다.
2. **업무 입력•조회(Business Input•Inquiry)**: 스크립트에 명시된 UI 셀렉터 조작 및 API 호출을 통해 실제 업무를 수행한다.
3. **완료•증적 기록(Completion•Evidence Recording)**: 트랜잭션 처리 결과와 수행 화면 스크린샷, 로그를 감사 이력으로 안전하게 영구 저장한다.
4. **예외•증적 이관(Exception•Evidence Transfer)**: 처리 불능 상태에 빠진 트랜잭션을 업무 담당자의 예외 큐로 안전하게 라우팅한다.

#### 한줄 요약
- 작업 할당부터 수행 완료 증적 보관까지 완벽한 기계적 파이프라인을 따르되, 사전 정의되지 않은 돌발 변수가 등장하면 즉시 실행을 멈추고 인간의 결정을 구하는 하이브리드 프로세스

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **참여형 봇(Attended Bot)**: 직원의 PC 내에 상주하며, 특정 이벤트나 사용자의 호출 트리거에 의해 실행되어 인간의 판단 및 승인 절차를 실시간으로 보조하는 봇이다.
- **무인형 봇(Unattended Bot)**: 독립된 서버 또는 가상 머신(VM)에 배치되어 인간의 개입 없이 스케줄러나 큐의 트리거에 따라 대규모 백오피스 업무를 24시간 연중무휴로 자동 실행하는 봇이다.
- **API 자동화(API Automation)**: UI 변경에 취약한 화면 조작(Scraping)을 배제하고, 공식적인 시스템 간 통신 규약(REST/SOAP 등)을 통해 직접 데이터를 교환하여 대용량 연계의 안정성과 속도를 극대화하는 방식이다.

</details>

| 업무 자동화 방식 | **참여형 봇(Attended Bot)** | **무인형 봇(Unattended Bot)** | **API 자동화(API Automation)** |
|:---|:---|:---|:---|
| 적용 기준 | 콜센터 상담, 결재 승인 등 인간의 인지적 판단이 필수적으로 결합되는 프론트오피스 업무 | 급여 정산, 데이터 배치 처리 등 대량의 정형 데이터와 고정된 규칙이 존재하는 백오피스 업무 | 공식적인 인터페이스가 제공되고 초고속 대용량 데이터 연계가 필요한 인프라 통신 환경 |
| 핵심 특징 | 사용자 단말에 상주하며 업무 프로세스의 일부 구간만을 보조적으로 자동화 | 독립된 가상 서버 환경에서 작업 큐 기반으로 엔드투엔드(End-to-End) 무인 실행 | 화면 렌더링 과정 없이 명확한 시스템 통신 계약(Contract)을 통해 애플리케이션 직접 호출 |
| 한계 | 직원의 마우스/키보드 조작과 봇의 화면 제어권 충돌 발생 가능성 | 잘못된 규칙 설정 시 비즈니스 오류의 대규모 확산 위험 및 권한 오용 리스크 | 레거시 시스템의 잦은 백엔드 변경 시 개발 및 유지보수 비용 크게 상승 |

> 요약: 프론트오피스의 사람 보조는 **참여형(Attended)**, 백오피스의 대량 룰 기반 업무는 **무인형(Unattended)**, UI 변경 리스크가 크고 안정적 연계가 필요하면 **API**를 도입하는 전략이 핵심이다.

#### 한줄 요약
- 사용자 세션 내에서 트리거를 받으면 참여형, 서버가 백그라운드에서 스케줄링으로 통제하면 무인형, UI 종속성을 탈피하려면 API 연동 기반의 자동화를 전략적으로 취사선택

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **봇 실행 중단(Bot Execution Halt)**: 대상 애플리케이션의 화면 레이아웃 업데이트나 DOM 구조 변경으로 인해 봇이 사전에 정의된 UI 요소를 찾지 못해 전체 자동화 프로세스가 멈춰버리는 가장 흔한 장애 유형이다.
- **셀렉터(Selector)**: 봇이 수많은 화면 요소 중 텍스트 박스, 버튼 등 자신이 상호작용해야 할 정확한 타겟을 식별하기 위해 사용하는 HTML 태그 속성이나 XML 경로(XPath)이다.
- **자격증명 금고(Credential Vault)**: 봇이 시스템 로그인에 사용하는 민감한 계정 정보와 비밀번호를 평문으로 스크립트에 하드코딩하지 않고, 강력한 알고리즘으로 암호화하여 런타임에만 동적으로 주입하는 안전한 중앙 보안 저장소이다.
- **업무 예외함(Business Exception Queue)**: 봇이 규칙에 따라 자동 처리할 수 없는 이상 데이터 건들을, 발생 원인 및 캡처 증적과 함께 격리 보관하여 인간 작업자에게 후속 처리를 인계하는 안전 대기열이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템 화면 UI 업데이트에 따른 빈번한 **봇 실행 중단(Bot Execution Halt)** 현상 | 불안정한 속성 배제 등 **셀렉터(Selector)** 추상화 적용 및 신규 배포 전 회귀 테스트(Regression Test) 의무화 | 스크립트 깨짐 현상 최소화 및 자동화 파이프라인의 유지보수성 획기적 향상 |
| 봇 전용 계정에 부여된 과도한 권한의 악용 및 탈취 위험성 | 하드코딩 금지, **자격증명 금고(Credential Vault)** 활용, 최소 권한 원칙(PoLP) 적용 및 봇 행위 로그 전면 감사 | 기밀 데이터 유출 방지 및 엔터프라이즈급 자격증명 보안 리스크 원천 차단 |
| 특정 트랜잭션의 비즈니스 룰 예외 건 무한 재시도 및 무한 루프 발생 | 예외 탐지 시 재시도 횟수 제한, **업무 예외함(Business Exception Queue)** 격리 및 즉각적인 인간 작업자 인계 프로세스 가동 | 시스템 과부하 및 오류의 연쇄 확산을 방지하여 전체 비즈니스 흐름 정상 유지 |
| 표준화되지 않고 예외가 난무하는 불안정 업무의 무리한 자동화 고착 | BPR(업무 재설계)을 통한 프로세스 표준화 및 단순화 선행 후 **로보틱 프로세스 자동화(RPA)** 순차 적용 | 빈번한 스크립트 수정으로 인한 매몰 비용 절감 및 자동화 ROI 극대화 |

#### 한줄 요약
- 콜센터 상담원이 고객과 통화하며 확인한 정보를 여러 분산된 레거시 시스템에 중복 입력하는 번거로움을 봇이 대신하여 데이터 정합성과 업무 효율을 동시 향상
