## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RPA (Robotic Process Automation, 로보틱 프로세스 자동화)**: 사람이 PC 화면에서 수행하던 정형화되고 규칙 기반의 반복적인 데이터 입력, 조회, 이관 등의 업무를 소프트웨어 봇(Software Bot)이 UI를 직접 제어하여 대신 수행하도록 하는 비침투적(Non-invasive) 업무 자동화 기술.
- **휴먼 에러 및 비효율적 수작업 위험(Human Error & Operational Inefficiency Risk)**: 다수의 레거시 시스템 간 복사·붙여넣기 수작업으로 인한 입력 오기, 정산 지연, 단순 반복 업무로 인한 고급 인력의 생산성 저하 위험.

</details>

- 정의/개념: 기존 시스템의 변경 없이 소프트웨어 봇(Bot)이 **정형화된 규칙 기반 반복 업무를 화면(UI) 레벨에서 자동 수행**하는 프로세스 자동화 기술
- 배경/필요성: 수작업 단순 반복 입력 및 데이터 이관 업무로 인한 **휴먼 에러(Human Error) 빈발, 업무 처리 지연 및 운영 인건비 낭비 위험** 직면

#### 한줄 요약

- 레거시 백엔드 수정 없이 오케스트레이터(Orchestrator)의 중앙 지휘 하에 소프트웨어 봇이 정형 업무를 24시간 365일 무중단 처리

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비침투성(Non-invasive Integration)**: 기존 레거시 시스템의 소스 코드나 데이터베이스를 수정하지 않고 사람이 보던 UI 화면의 셀렉터(Selector)를 인식하여 작동하는 특성.
- **오케스트레이터(Orchestrator)**: 수십~수백 대의 봇에 대한 작업 스케줄링, 트랜잭션 큐 관리, 계정 자격증명(Credential Vault), 감사 로그를 중앙 집중 제어하는 관제 서버.

</details>

- 기존 IT 인프라와 백엔드를 건드리지 않고 수주 내 구축하는 **신속한 구축 및 비침투성**
- 작업 큐(Queue) 기반으로 업무량을 동적 분배하는 **중앙 집중식 오케스트레이션**
- 정형 업무는 봇이 처리하고 예외 상황만 사람이 개입하는 **Human-in-the-Loop 예외 관리** #### 한줄 요약

- 비침투적 UI 조작, 중앙 오케스트레이터 관제, 예외 큐 이관을 결합하여 업무 처리 속도와 정확도를 극대화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RPA 4대 핵심 아키텍처 요소**: Orchestrator(중앙 관제), Software Bot(실행 엔진), UI Selector/API(연계 인터페이스), Human Exception Queue(예외 처리기).

</details>

```text
[ RPA(로보틱 프로세스 자동화) 중앙 관제 및 실행 아키텍처 구조도 ]

 1. [ 중앙 관제 플랫폼 (RPA Orchestrator) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • 스케줄러 + 트랜잭션 작업 큐(Work Queue) + Credential Vault│
    │  • 실시간 봇 상태 모니터링 및 감사 로그(Audit Log) 수집    │
    └────────────────────────────┬────────────────────────────────┘
                                 │ (작업 할당 및 암호화 인증서 주입)
                                 ▼
 2. [ 소프트웨어 봇 실행 계층 (Software Bot: Attended / Unattended) ]
    ┌────────────────────────────┴────────────────────────────┐
    │ (UI 레벨 조작: Click, Type)                             │ (백엔드 직접 연동)
    ▼                                                         ▼
 3. [ 레거시 시스템 화면 (UI Selectors) ]    4. [ 비즈니스 API / DB ]
    • ERP, 그룹웨어, 엑셀, 웹 브라우저       • REST API, SQL Direct Query
    └────────────────────────────┬────────────────────────────┘
                                 │
                                 ▼ (비즈니스 예외 발생 시)
 5. [ 사람 개입 계층 (Human Exception Queue: 담당자 수동 승인) ]
```

선의 의미: Orchestrator가 봇에 작업을 할당하여 UI 및 API로 업무를 처리하고, 예외 발생 시 담당자 큐로 이관하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 오케스트레이터 (Orchestrator) | 봇 스케줄링, **작업 큐(Queue) 분배, 계정 암호(Vault) 주입, 감사 로그 중앙 통제** |
| 소프트웨어 봇 (Bot) | 사전 정의된 워크플로우 스크립트에 따라 **UI 조작, 데이터 추출, 양식 입력을 대행** |
| UI 셀렉터 (Selector) | 화면의 버튼, 입력 필드의 **HTML/DOM, UI Automation 속성을 식별하여 조작** |
| 자격증명 금고 (Vault) | 봇이 시스템에 로그인할 수 있도록 **ID/PW를 AES 암호화 보관하고 런타임에만 동적 주입** |
| 예외 처리 큐 (Exception) | 봇이 처리하지 못한 비즈니스 예외를 **담당자에게 화면 캡처와 함께 이관하여 승인 유도** |

#### 한줄 요약

- 오케스트레이터, 봇, 셀렉터, 자격증명 금고, 예외 처리 큐가 결합하여 RPA 시스템을 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RPA 트랜잭션 5단계 처리 파이프라인**: 작업 큐 아이템 인출 $\to$ 보안 자격증명 획득 $\to$ UI 조작 및 데이터 처리 $\to$ 정상 완료 증적 보관 $\to$ 예외 발생 시 사람 이관.

</details>

```text
[ RPA 봇 업무 처리 및 Human-in-the-Loop 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. Orchestrator 작업 큐에서 Item 인출  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. Credential Vault에서 암호화 계정 획득│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. ERP 및 엑셀 UI 자동 조작/입력 수행 │
 ├───────────────────┬────────────────────┤
 │ 정상 완료         │ 비즈니스 예외 발생 │
 │ 4A. 감사 로그 및  │ 4B. 화면 캡처 후   │
 │     증적 스크린샷 │     담당자 큐 이관 │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 트랜잭션 성공 완료 및 다음 작업 대기│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 작업 인출: 새벽 2시 Unattended Bot이 Orchestrator 작업 큐에서 '법인카드 전표 500건' 중 1번 아이템을 인출.
2. 계정 주입: 사내 ERP 로그인에 필요한 관리자 비밀번호를 CyberArk Vault로부터 메모리에 안전하게 로드.
3. 자동 입력: ERP 전표 입력 화면을 열고 셀렉터를 통해 가맹점명, 금액, 부가세를 자동으로 기입.
4. 예외 분기: 100만 원 초과 전표 중 사유서 첨부가 누락된 비즈니스 예외 발견 시 즉시 화면 캡처와 함께 실패 사유 기록.
5. 사람 이관: 정상 건은 승인 완료 증적을 저장하고, 예외 건은 재무팀 담당자 화면의 Exception Queue로 즉시 토스.

#### 한줄 요약

- 작업 인출 $\to$ 계정 획득 $\to$ 자동 입력 $\to$ 증적 보관 $\to$ 예외 이관의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Attended vs Unattended vs API 자동화**: 사람 보조형(Attended), 백그라운드 서버 배치형(Unattended), 시스템 직결형(API).

</details>

| 구분 | 유인 봇 (Attended Bot) | 무인 봇 (Unattended Bot) | 백엔드 API 자동화 (Direct API) |
|:---|:---|:---|:---|
| **적용 기준** | 상담원, 지점 창구 등 사람의 판단과 상호작용이 필요한 프론트 업무 | 야간 대량 정산, 데이터 이관 등 사람 개입 없는 백오피스 대량 업무 | 시스템 간 공식 인터페이스(REST API)가 이미 열려있는 표준 연계 |
| **핵심 특징** | **사용자 PC에서 단축키/이벤트로 실행, 사람과 화면 공유** | **전용 가상머신(VM)에서 24시간 스케줄/큐 기반 자율 실행** | **화면 UI 변경에 무관하게 초고속 대용량 트랜잭션 직접 통신** |
| **한계** | 봇 실행 중 사용자의 마우스/키보드 조작 충돌 발생 | 화면 변경이나 팝업 시 대량 트랜잭션 일괄 실패 위험 | 레거시 시스템 수정 개발 비용 및 계약 변경 일정 소요 |

#### 한줄 요약

- 창구 업무는 Attended, 대량 배치는 Unattended, 장기적 안정 연계는 API 자동화를 채택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **UI 셀렉터 파손(Selector Breakage)**: 웹 브라우저 업데이트나 사내 ERP UI 리뉴얼로 인해 HTML 태그 ID나 위치가 바뀌어 봇이 버튼을 찾지 못하고 뻗어버리는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ERP 화면 개편 시 고정 좌표/ID 변경으로 봇 대량 중단 | **절대 좌표 대신 `동적 앵커(Anchor) 및 시각 AI 인식(Computer Vision)` 적용** | UI 변경 시 봇 유지보수 비용 70% 절감 |
| 봇 계정 권한이 과도하게 부여되어 데이터 오기입/삭제 사고 | **`최소 권한 원칙(PoLP)` 및 Credential Vault 동적 일회용 토큰 적용** | 봇 계정 탈취 및 오용 원천 차단 |
| 예외 발생 시 무한 루프 재시도로 시스템 DB 락(Lock) 유발 | **최대 재시도(3회) 제한 및 즉각 `Business Exception Queue` 이관** | 시스템 과부하 및 교착상태 방지 |

#### 한줄 요약

- 동적 셀렉터 적용, 최소 권한 원칙, 예외 큐 이관을 통해 RPA 운영 안정성을 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **하이퍼오토메이션(Hyperautomation)과 AI 에이전트**: RPA에 LLM과 프로세스 마이닝(Process Mining)을 결합하여 복잡한 비정형 문서 처리와 의사결정까지 스스로 수행하는 지능형 자동화.

</details>

- **RPA 로보틱 프로세스 자동화** 기반 레거시 시스템의 한계를 극복하고 기업의 디지털 전환을 가속하는 핵심 생산성 도구이며, 체계적인 오케스트레이터 중앙 관제와 AI 결합을 통해 지능형 하이퍼오토메이션으로 발전시켜야 함

#### 한줄 요약

- 비침투적 UI 조작과 중앙 오케스트레이터 관제를 통해 휴먼 에러를 제거하고 업무 생산성을 완성
