## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RPA (Robotic Process Automation)**: 사람이 PC 화면에서 수행하던 정형화되고 반복적인 업무를 소프트웨어 봇이 UI/API를 제어하여 대신 수행하는 비침투적 자동화 기술.
- **Non-invasive (비침투성)**: 레거시 시스템의 백엔드 소스코드나 DB를 수정하지 않고 기존 UI 레이어를 조작하여 연동하는 특성.

</details>

- 정의/개념: 기존 시스템의 수정 없이 소프트웨어 봇이 **정형화된 규칙 기반 반복 업무를 UI 및 API 레벨에서 자동 대행하는 비침투적 자동화 기술**
- 배경/필요성: 기업의 수많은 레거시 시스템 간 표준 연동 API 부재로 인해 단순 반복적인 전표 입력, 데이터 이관, 정산 검증 업무를 수작업으로 처리함에 따라 발생하는 막대한 인건비 손실, 휴먼 에러(오기입/누락) 및 야간/주말 업무 처리 지연을 해결하기 위해, 기존 시스템의 백엔드 수정 없이 UI 및 API 계층을 조작하는 비침투적(Non-invasive) 소프트웨어 봇과 중앙 오케스트레이터를 도입하여 **24시간 365일 무중단 업무 처리, 휴먼 에러 0건 및 운영 비용의 획기적 절감**을 달성할 필요

#### 한줄 요약
- 중앙 오케스트레이터의 통제 하에 소프트웨어 봇이 정형 업무를 24시간 365일 무중단 처리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Orchestrator**: 다수의 봇에 대한 작업 스케줄링, 트랜잭션 큐 관리, 계정 금고(Vault), 감사 로그를 중앙 집중 제어하는 관제 서버.
- **Human-in-the-Loop**: 정형화된 업무는 봇이 자동 처리하고, 규칙 밖의 예외 상황(Exception)만 사람이 수동 승인/처리하는 협업 모델.

</details>

- 기존 IT 인프라와 백엔드를 건드리지 않고 신속히 도입하는 **비침투성(Non-invasive)**
- 작업 큐(Queue) 기반으로 업무량을 동적 분배하는 **중앙 집중식 오케스트레이션**
- 정형 업무는 봇이 처리하고 예외 상황만 사람이 개입하는 **Human-in-the-Loop 예외 관리**

#### 한줄 요약
- 비침투성, 중앙 오케스트레이션, Human-in-the-Loop 거버넌스를 통해 업무 자동화를 구현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RPA 4대 아키텍처**: Orchestrator(중앙 관제), Software Bots(유인/무인 봇), UI Selectors/Vault(화면 인식 및 암호 금고), Exception Queue(예외 큐).

</details>

```text
[RPA 구성]
|-- 오케스트레이터
|-- 소프트웨어 봇
|-- UI 셀렉터
|-- 자격증명 금고
`-- 예외 처리 큐
```

선의 의미: 계층 및 Orchestrator가 봇에 작업을 할당하여 UI 및 API로 업무를 처리하고 예외 발생 시 담당자 큐로 이관하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **오케스트레이터 (Orchestrator)**| 봇 스케줄링, **작업 큐(Queue) 분배, 계정 암호(Vault) 주입, 감사 로그 중앙 통제**| 중앙 관제 서버 |
| **소프트웨어 봇 (Bot)** | 사전 정의된 워크플로우 스크립트에 따라 **UI 조작, 데이터 추출, 양식 입력을 대행** | 유인/무인 실행체 |
| **UI 셀렉터 (Selector)** | 화면의 버튼, 입력 필드의 **HTML/DOM, UI Automation 속성을 식별하여 조작** | 화면 인식 엔진 |
| **자격증명 금고 (Vault)** | 봇이 시스템에 로그인할 수 있도록 **ID/PW를 AES 암호화 보관하고 런타임에 동적 주입** | CyberArk 연동 |
| **예외 처리 큐 (Exception)** | 봇이 처리하지 못한 비즈니스 예외를 **담당자에게 화면 캡처와 함께 이관하여 승인 유도** | Human-in-the-Loop |

#### 한줄 요약
- 오케스트레이터가 스케줄·계정·감사를 중앙에서 쥐고 봇은 실행만 맡으므로, 봇 수가 수백 개로 늘어도 통제 지점은 하나로 유지된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RPA 트랜잭션 5단계**: 작업 큐 아이템 인출 $\to$ 보안 자격증명 획득 $\to$ UI 조작 및 데이터 입력 $\to$ 정상 완료 증적 보관 $\to$ 예외 발생 시 사람 이관.

</details>

```text
RPA 무인 봇 새벽 배치 트랜잭션 가동
        │
   1. [작업 인출] Orchestrator 작업 큐에서 '법인카드 전표 500건' 중 1번 아이템 인출
        │
   2. [계정 획득] 사내 ERP 로그인에 필요한 관리자 비밀번호를 Vault로부터 안전하게 로드
        │
   3. [자동 입력] ERP 전표 입력 화면을 열고 셀렉터를 통해 가맹점명, 금액, 부가세 자동 기입
   ┌────┴───────────────────────────┐
  정상 완료                         비즈니스 예외 발생
   │                                 │
4A. [감사 로그 및 증적 저장]        4B. [화면 캡처 및 담당자 이관]
   성공 스크린샷과 트랜잭션 로그 기록   사유서 누락 건을 담당자 Exception Queue로 전송
   │                                 │
   └────┬────────────────────────────┘
        ▼
   5. 트랜잭션 완료 후 다음 큐 아이템 자동 인출 및 처리 대기
```

#### 한줄 요약
- 봇이 처리하지 못한 건은 실패가 아니라 예외 큐로 넘어가므로, 자동화율을 100%까지 끌어올리는 비용 대신 예외 건만 사람이 감당하는 구조가 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Attended vs Unattended vs API 직접 연계**: 유인 봇(Attended), 무인 봇(Unattended), 백엔드 시스템 직접 연계(Direct API).

</details>

| 비교 항목 | 유인 봇 (Attended Bot) | 무인 봇 (Unattended Bot) | 백엔드 API 직접 연동 |
|:---|:---|:---|:---|
| 핵심 적용 대상 | **상담원, 지점 창구 등 사람과의 상호작용** | **야간 대량 정산, 데이터 이관 등 백오피스** | **시스템 간 표준 REST API가 열린 영역** |
| 봇 실행 환경 | **사용자 PC에서 단축키/이벤트로 화면 공유 실행** | **전용 가상머신(VM)에서 24시간 자율 실행** | **서버 간 백그라운드 HTTP/gRPC 직접 통신** |
| UI 변경 민감도 | 보통 (사용자가 화면 오류 즉시 인지) | 높음 (화면 개편 시 대량 트랜잭션 실패) | **전무 (화면 UI 변경과 100% 무관)** |
| 구축 비용 및 기간 | 낮음 (수일~수주 내 단독 자동화) | 중간 (가상머신 및 관제 인프라 필요) | 높음 (레거시 시스템 개발 및 일정 소요) |

#### 한줄 요약
- 창구 업무는 Attended, 대량 배치는 Unattended, 장기적 안정 연계는 API 연동을 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Selector Breakage**: 웹 브라우저 업데이트나 ERP UI 리뉴얼로 인해 HTML 태그 ID나 위치가 바뀌어 봇이 멈추는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ERP 화면 개편 시 고정 좌표/ID 변경으로 봇 대량 중단 | **절대 좌표 대신 `동적 앵커(Anchor) 및 시각 AI 인식(Computer Vision)` 적용** | UI 변경 시 봇 유지보수 비용 70% 절감 |
| 봇 계정 권한이 과도하게 부여되어 데이터 오기입/삭제 사고 | **`최소 권한 원칙(PoLP)` 및 Credential Vault 동적 일회용 토큰 적용** | 봇 계정 탈취 및 오용 원천 차단 |
| 예외 발생 시 무한 루프 재시도로 시스템 DB 락(Lock) 유발 | **최대 재시도(3회) 제한 및 즉각 `Business Exception Queue` 이관** | 시스템 과부하 및 교착상태 방지 |
| 수백 개 봇의 무분별한 난립으로 인한 섀도우 IT 위험 | **중앙 COE(Center of Excellence) 조직 기반 봇 등록/승인 거버넌스** | 전사 자동화 자산 통제권 확보 |

#### 한줄 요약
- 네 대책은 화면을 통해 자동화한 대가인 UI 취약성·권한 과다·봇 난립을 동적 인식과 거버넌스로 되사는 선택이며, 근본 해법인 API 연동은 별도 개발 비용을 요구한다.

## Ⅶ. 결론

- 엔터프라이즈 디지털 전환(DX)과 하이퍼오토메이션(Hyperautomation)의 출발점으로서 단순 업무를 넘어 생성형 AI/문서 OCR과 결합된 지능형 프로세스 자동화(IPA)로 빠르게 진화하고 있으며, 실무 구축 시에는 **업무 특성별 유인(Attended)/무인(Unattended) 봇 분기, 화면 변경에 강인한 AI 시각 인식(Computer Vision) 및 동적 앵커 셀렉터 적용, Credential Vault 기반 계정 보안 통제, 예외 발생 시 Human-in-the-Loop 이관 및 전사 COE(Center of Excellence) 거버넌스 수립**을 결합하여 장기적 유지보수성과 확장성을 완성

#### 한줄 요약
- RPA는 비침투적 UI 조작과 중앙 오케스트레이션을 통해 휴먼 에러를 제거하고 업무 효율성을 극대화하는 핵심 프로세스 혁신 기술이다.
