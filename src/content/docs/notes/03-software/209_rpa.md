## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **RPA (Robotic Process Automation)**: 사람의 반복•규칙 기반 화면 업무를 Software Bot이 수행하는 기술
- **Software Bot**: UI•File•API를 Script 순서에 따라 조작하는 가상 Worker

</details>

- 정의/개념: Legacy 변경 없이 Bot으로 규칙 기반 업무를 자동화하는 **RPA**
- 배경/필요성: 반복 입력의 **처리 지연•Human Error•인건비 증가** 발생

#### 한줄 요약

- 정형 반복 업무는 Bot이 처리하고 **예외 판단**은 사람에게 이관

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **Orchestrator**: Bot 배포•Schedule•Queue•Credential•Log를 중앙 통제하는 Server

</details>

- **비침투성**: Legacy Backend 변경 없이 UI 조작
- **중앙 통제**: Orchestrator로 Bot•권한•Log 관리
- **Queue 처리**: Transaction을 상태별 분배•재처리
- **후보 발굴**: Process Mining으로 반복•병목•ROI 분석

#### 한줄 요약

- UI 기반 신속 도입과 **Orchestrator 중앙 통제** 결합

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **Human Operator**: Bot이 처리하지 못한 업무 예외를 판단•승인하는 담당자

</details>

```text
[RPA]
 ├── [Orchestrator | Schedule•Queue•권한•Log]
 ├── [Software Bot | Script 실행]
 ├── [UI | 화면 요소 조작]
 ├── [API | 안정적 Backend 연계]
 └── [Human Operator | 예외 판단•승인]
```

| 구성요소 | 책임 |
|---|---|
| Orchestrator | Bot•Schedule•Queue•Credential•**Log 통제** |
| Software Bot | Script 규칙에 따른 **업무 실행** |
| UI | Legacy 화면의 입력•조회 **접점** 제공 |
| API | 화면 변경과 독립된 **통신 계약** 제공 |
| Human Operator | 업무 예외의 **판단•승인•Rule 보완** |

#### 한줄 요약

- 중앙 관제가 Bot을 지휘하고 **예외 Queue**는 사람에게 연결

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **Business Exception Queue**: 자동 처리할 수 없는 업무 건과 증적을 보관하는 Queue

</details>

```text
[업무 Queue 입력]
          │
          ▼
[1. 작업•Credential 전달]
          │
          ▼
[2. 업무 입력•조회]
          │
          ▼
┌─────────[결과 판정]─────────┐
│ 정상: 3. 완료•증적 기록    │
│ 예외: 4. 예외•증적 이관    │
└─────────────────────────────┘
```

### 동작 원리

1. **작업•Credential 전달**: 가용 Bot에 최소 권한과 Item 할당
2. **업무 입력•조회**: UI Selector 또는 API로 업무 수행
3. **완료•증적 기록**: 결과•화면•Log를 Audit 이력으로 보존
4. **예외•증적 이관**: 실패 원인과 증적을 담당자 Queue로 전달

#### 한줄 요약

- 정상 건은 증적을 남기고 **Rule 밖 예외**는 즉시 사람에게 이관

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **Attended Bot (참여형 봇)**: 사용자 호출과 판단을 결합해 Front Office 업무를 보조하는 Bot

</details>

| 비교 항목 | Attended Bot | Unattended Bot | API 자동화 |
|---|---|---|---|
| 적용 | 사람 판단 포함 업무 | 대량 규칙 기반 업무 | 공식 Interface 보유 |
| 실행 | 사용자 Session | Server•Schedule•Queue | System 간 직접 호출 |
| 한계 | 입력 제어권 충돌 | 오류 대량 확산 | 개발•계약 변경 비용 |

#### 한줄 요약

- 사람 보조는 Attended, Batch는 Unattended, 안정 연계는 **API** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **Credential Vault (자격증명 금고)**: Bot 계정을 암호화해 Runtime에만 주입하는 저장소

</details>

| 고려사항 | 대책 |
|---|---|
| UI 변경으로 Bot 중단 | Selector 추상화와 **회귀 Test** 적용 |
| Bot 계정 권한 오용 | Vault•최소 권한•**행위 Audit** 적용 |
| 업무 예외 무한 재시도 | 재시도 상한과 **Exception Queue** 이관 |
| 불안정 업무 자동화 | BPR로 표준화 후 **RPA** 적용 |

#### 한줄 요약

- UI 변화•Credential•예외•업무 표준화를 **운영 통제**로 관리

## Ⅶ. 결론

<details><summary>쉽게 이해하기 (학습용)</summary>

- 공식 API가 있으면 직접 연결하고, API가 없는 안정된 반복 화면에만 Bot을 둔다.

</details>

- 공식 Interface는 **API**, 안정된 Legacy 반복 UI만 RPA 적용
