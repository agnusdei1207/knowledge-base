## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시프트 레프트 및 자동 보안 검증(Shift-Left & SAST/DAST/SCA)**: 보안 점검을 기획/코딩 초기 단계로 전진 배치하고 정적/동적/오픈소스 검사를 자동화하는 기법.
- **사후 보안 검사 및 릴리스 지연(Late-Stage Gate & Delay)**: 운영 배포 직전에야 보안 취약점이 발견되어 개발 일정 전체가 마비되고 패치가 지연되는 한계.

</details>

- 정의/개념: 기획부터 운영까지 파이프라인 전 단계에 보안 검증을 내재화하는 **시프트 레프트(Shift-Left) 및 자동 보안 게이트(SAST/DAST/SCA)** 통합 체계
- 배경/필요성: 릴리스 직전 사후 보안 검사 시 발생하는 **대규모 코드 재작업 및 출시 지연과 제로데이 취약점 방치 위험** 직면

#### 한줄 요약

- 코딩 단계부터 파이프라인 전체에 자동화 보안 검사를 내재화하여 배포 직전 보안 병목을 제거

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **자동 보안 게이트(Automated Security Gate)**: CI/CD 파이프라인에서 보안 취약점이 기준을 초과하면 자동으로 파이프라인을 차단하는 보안 검증 관문.
- **보안 공동 책임(Shared Security Responsibility)**: 개발자·보안팀·운영팀 모두가 보안 책임을 분담하여 보안을 특정 조직의 전담 영역이 아닌 팀 전체의 공동 과제로 다루는 문화.

</details>

- 보안 검증을 개발 초기로 앞당기는 **Shift-Left Security** 원칙 적용
- 보안 정책을 코드로 정의하고 파이프라인에서 자동 검증하는 **Policy as Code + 자동 보안 게이트** 구현
- 개발·보안·운영의 **보안 공동 책임** 문화 정착

#### 한줄 요약

- Shift-Left·PaC·자동 보안 게이트·공동 책임 문화로 보안을 파이프라인 전 단계에 내재화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SAST / DAST / SCA**: 정적 분석(SAST: 소스 코드 취약점 탐지)·동적 분석(DAST: 실행 환경 모의 침투 테스트)·소프트웨어 구성 분석(SCA: 오픈소스 의존성 취약점 탐지)의 보안 검증 도구 체계.

</details>

```text
[ DevSecOps 파이프라인 보안 게이트 구조 ]
IDE (코딩)
   └─ 보안 플러그인: 하드코딩 비밀번호·자격 증명 검출
   │
Git Pre-commit
   └─ 비밀 정보(Secret) 커밋 차단
   │
CI 빌드 단계
   ├─ SAST: 소스 코드 정적 분석 (XSS·SQL Injection 탐지)
   └─ SCA: 오픈소스 의존성 취약점 스캔
   │
컨테이너 이미지 스캔 (Trivy)
   └─ Base OS·패키지 CVE 취약점 탐지
   │
자동 보안 게이트
   └─ Critical·High 취약점 발견 시 파이프라인 차단
   │ 통과
운영 배포
   │
DAST + 런타임 관측
   └─ 배포 후 모의 침투 테스트 및 이상 행위 감시
```

선의 의미: 단계 간 화살표는 파이프라인 진행 방향, 각 단계의 가지(`└─`)는 해당 보안 검사 수행 내용

| 구성요소 | 책임 |
|:---|:---|
| **위협 모델링** | 기획 단계에서 주요 위협 벡터와 방어선 사전 정의 |
| **SAST / SCA** | CI 단계에서 소스 코드 취약점·오픈소스 위험 탐지 |
| **자동 보안 게이트** | 취약점 기준 초과 시 파이프라인 자동 차단 |
| **DAST** | 운영 환경 배포 후 실행 상태 모의 침투 테스트 |
| **런타임 보안 관측** | 운영 중 이상 행위·침해 시도 실시간 감시 |

#### 한줄 요약

- 코딩→커밋→빌드→이미지 스캔→보안 게이트→배포→DAST·감시의 전 단계에 보안 검증 배치

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **컨테이너 이미지 스캔(Container Image Scanning)**: 배포 전 컨테이너 이미지의 기반 OS·패키지 CVE 취약점을 Trivy 등의 도구로 탐지하는 보안 검증 단계.

</details>

```text
1. Git Commit (Pre-commit Hook)
   └─ 하드코딩 자격 증명(API Key·비밀번호) 차단
   │
   ▼
2. CI 빌드: SAST·SCA 자동 실행
   └─ XSS·SQL Injection·취약 오픈소스 탐지
   │
   ▼
3. 컨테이너 이미지 스캔 (Trivy)
   └─ OS·패키지 CVE 취약점 탐지
   │
   ▼
4. 자동 보안 게이트 판정
   ├─ 통과: 운영 환경 배포
   └─ Critical·High 탐지: 파이프라인 차단·개발자 알림
   │
   ▼
5. 배포 후 DAST 모의 침투 + 런타임 이상 행위 감시
```

**동작 원리** 1. **Pre-commit 검사**: 커밋 단계에서 자격 증명 하드코딩 등 비밀 정보 포함 여부 차단
2. **SAST/SCA**: CI 파이프라인에서 코드 취약점과 오픈소스 의존성 취약점 자동 탐지
3. **이미지 스캔**: 컨테이너 이미지 빌드 후 CVE 취약점 탐지
4. **보안 게이트**: 정책 기준 위반 시 파이프라인 자동 차단, 개발자에게 즉시 피드백
5. **런타임 감시**: 배포 후 DAST·이상 행위 탐지로 운영 중 보안 위협 지속 모니터링

#### 한줄 요약

- 커밋→SAST/SCA→이미지 스캔→보안 게이트→배포→DAST·감시의 3중 자동화 보안 검증 흐름

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전통 사후 보안 vs DevSecOps**: 배포 완료 후 수동 보안 점검을 수행하는 방식과 파이프라인 전 단계에 자동화 보안 검사를 내재화하는 방식의 대비.

</details>

| 구분 | 전통 보안 (사후 점검) | DevSecOps (지속적 내재화) |
|:---|:---|:---|
| 검사 시점 | 배포 전 단발성 수동 점검 | **커밋 단계부터 전 파이프라인 자동 검증** |
| 피드백 속도 | 완료 코드 전면 재작업으로 고비용 | **커밋 단위 즉각 피드백·최소 수정** |
| 책임 주체 | 전담 보안팀 단독 | **개발·보안·운영 공동 책임** |
| 도구 자동화 | 수동 점검·문서 기반 | **SAST·SCA·DAST·PaC 자동화** |

#### 한줄 요약

- 사후 점검의 고비용·배포 지연 문제를 DevSecOps의 Shift-Left 자동화와 공동 책임으로 해소

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **보안 챔피언(Security Champion)**: 개발팀 내 보안 인식이 높은 구성원을 선정하여 보안팀과 개발팀 간 가교 역할을 수행하고 보안 문화를 내부에서 전파하는 역할.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 보안 도구의 오탐(False Positive)으로 정상 빌드 차단 | 룰셋 최적화 및 검증된 오탐에 대한 **예외 처리(Exclusion)** 허용 | 파이프라인 생산성 저하 방지 |
| 전체 보안 스캔으로 CI 파이프라인 실행 시간 과다 | **증분 스캔(변경 코드 대상)** + 야간 정기 전체 스캔으로 분리 | 빠른 피드백 유지와 심층 검증 동시 달성 |
| 개발자의 보안 도구 회피 시도 | **보안 챔피언** 육성·IDE 보안 플러그인 기본 제공 | 강제 없이 보안 의식이 자연스럽게 정착 |

#### 한줄 요약

- 오탐은 예외 처리로, 속도는 증분 스캔으로, 보안 문화는 보안 챔피언 육성으로 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DevSecOps 성숙도 평가**: 위협 모델링 수행 여부·SAST/SCA/DAST 자동화 수준·런타임 방어 체계·공동 책임 문화를 기준으로 성숙도를 평가하는 판단 기준.

</details>

- Shift-Left 보안 내재화(SAST)로 개발 단계 결함을 차단하고, 런타임 관측(DAST)으로 운영 중 위협을 방어하는 **DevSecOps 양방향 보안 체계** 적용

#### 한줄 요약

- 보안은 배포 후 보완이 아닌 개발 초기부터 파이프라인에 내재화하는 설계 구조로 적용
