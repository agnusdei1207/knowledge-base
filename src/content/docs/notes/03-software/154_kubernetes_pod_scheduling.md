## 미리 알고가기

- **파드(Pod)**: 같은 노드에 함께 배치되는 최소 컨테이너 실행 단위
- **쿠버네티스 API 서버(kube-apiserver)**: 파드·노드 객체를 검증·저장하고 바인딩 변경을 받는 제어면 진입점
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 쿠버네티스 객체를 정해진 형식으로 조회·변경하는 규약
- **쿠버네티스 스케줄러(Kubernetes Scheduler)**: 미배치 파드의 조건을 만족하는 노드를 선택해 바인딩하는 제어면 구성요소
- **미배치 파드(Unscheduled Pod)**: 실행 노드가 정해지지 않아 스케줄링 큐에서 선택을 기다리는 파드
- **자원 요청값·할당 가능량(Resource Request·Allocatable)**: 요청값은 포드 예약량이고 할당 가능량은 노드가 포드에 배정할 수 있는 CPU·메모리 총량
- **중앙처리장치(Central Processing Unit, CPU)**: 스케줄러가 요청값과 노드 할당 가능량을 비교하는 처리 자원
- **필터·점수(Filter·Score)**: 필터는 필수 조건 위반 노드를 제외하고 점수는 남은 노드를 선호 규칙으로 순위화한다.
- **테인트·톨러레이션(Taint·Toleration)**: 테인트는 노드의 거부 조건이고 톨러레이션은 파드가 그 조건을 허용한다는 선언
- **친밀도(Affinity)**: 파드·노드 특성에 따른 공동·분리 배치의 필수 조건과 선호를 표현하는 규칙
- **토폴로지 분산(Topology Spread)**: 영역·노드별 파드 수 편차를 제한해 복제본을 분산하는 규칙
- **큐 정렬(QueueSort)**: 우선순위와 대기 상태로 다음에 처리할 파드 순서를 정하는 스케줄링 단계
- **예약·허가·바인딩(Reserve·Permit·Bind)**: 선택 노드 자원을 임시 예약하고 실행을 허가한 뒤 파드에 노드 이름을 기록하는 단계
- **그래픽처리장치(Graphics Processing Unit, GPU)**: 파드가 확장 자원으로 요청할 수 있는 병렬 연산 가속기
- **스케줄링 프레임워크(Scheduling Framework)**: 필터·점수·예약·허가·바인딩 단계를 플러그인으로 확장하는 실행 구조
- **스케줄링 캐시(Scheduling Cache)**: 파드·노드의 최신 상태를 보관해 배치 판단에 제공하는 메모리 저장소
- **수직형 파드 오토스케일러(Vertical Pod Autoscaler, VPA)**: 사용 이력으로 파드의 CPU·메모리 요청값을 추천하거나 갱신하는 제어기
- **기아(Starvation)·축출(Eviction)**: 낮은 우선순위 작업이 계속 실행 기회를 얻지 못하는 현상과 실행 중인 파드를 노드에서 제거하는 동작
- **반친밀도(Anti-affinity)**: 같은 특성의 파드를 서로 다른 노드·영역에 분리 배치하는 규칙

## Ⅰ. 개요

- 정의/개념: 필수 조건으로 노드를 거르고 선호 점수로 **실행 노드**를 선택하는 배치 절차
- 배경/필요성: 수동 배치는 노드 **용량 편중·필수 정책 위반** 유발

### 쉽게 이해하기 (학습용)
- 좌석 배정처럼 필수 조건에 맞지 않는 노드를 먼저 제외한 뒤 남은 후보의 점수를 비교하면 대기 원인과 선택 이유가 분명해진다.

## Ⅱ. 특징

- **필수·선호 분리** 기반 후보 선별
- **자원 요청값·할당 가능량** 기반 수용량 계산
- **플러그인 단계** 기반 정책 확장

### 쉽게 이해하기 (학습용)
- GPU처럼 반드시 필요한 조건은 필터에 두고 같은 영역 선호처럼 선택 가능한 조건은 점수에 두어야 파드가 불필요하게 대기하지 않는다.

## Ⅲ. 구조 및 구성요소

```mermaid
block
    columns 1
    A["스케줄링 큐·캐시"]
    B["Filter 플러그인"]
    C["Score 플러그인"]
    D["Reserve·Permit"]
    E["Bind 플러그인"]
    A --- B
    B --- C
    C --- D
    D --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 스케줄링 큐·캐시 | 파드 순서·**노드 상태 제공** |
| Filter 플러그인 | **필수 배치 조건** 검사 |
| Score 플러그인 | 후보 노드 **선호 순위 계산** |
| Reserve·Permit | **선택 노드 예약·실행 허가** |
| Bind 플러그인 | **파드·노드 관계** 기록 |

### 쉽게 이해하기 (학습용)

- 대기열은 접수 창구, 필터는 입장 조건 검사, 점수는 좌석 선호 계산, 바인딩은 최종 좌석표 기록에 해당한다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant Q as 스케줄링 큐
    participant S as 스케줄러
    participant F as 스케줄링 프레임워크
    participant A as API 서버
    Q->>S: 1. 미배치 파드
    S->>F: 2. 필수 조건·선호 규칙
    F-->>S: 3. 후보 노드·점수
    S->>F: 4. 선택 노드·예약 조건
    F->>A: 5. 파드·노드 바인딩
```

**동작 원리**

1. **미배치 파드**: 우선순위·대기 상태에 따라 다음 배치 대상 선택
2. **필수 조건·선호 규칙**: 요청량·테인트·친밀도 조건 전달
3. **후보 노드·점수**: 필수 조건 통과 노드의 선호 순위 산출
4. **선택 노드·예약 조건**: 가정 자원 확보와 실행 허가
5. **파드·노드 바인딩**: 선택 노드 이름의 API 기록

### 쉽게 이해하기 (학습용)

- 파드 하나를 대기열에서 꺼낸 뒤 실행 불가능한 노드를 버리고 남은 후보를 채점해 가장 높은 노드를 객체에 기록한다.

## Ⅴ. 종류 및 비교

| 스케줄링 단계 | Filter | Score |
|:---|:---|:---|
| 적용 기준 | **실행 가능 여부 판정** | **가능 노드 선호 순위** |
| 핵심 특징 | 자원·필수 **친밀도·테인트 검사** | 자원 균형·**분산 점수** |
| 한계 | 조건 충돌 시 **장기 미배치** | **가중치 편향·노드 집중** |

### 쉽게 이해하기 (학습용)
- 필터 조건을 지나치게 좁히면 후보 자체가 사라지고 점수 조건만 바꾸면 파드는 실행되면서 배치 위치만 달라진다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 실사용량과 다른 **요청값**으로 노드 낭비·경합 | 사용 분포·**VPA 권고**로 요청값 산정 | **자원 낭비·노드 경합** 감소 |
| 친밀도·테인트의 **필수 조건 충돌**로 후보 소멸 | 미배치 사유 확인 후 **필수 조건 최소화** | **장기 미배치** 해소 |
| 낮은 우선순위 파드의 반복 축출로 **기아** 발생 | 우선순위 등급·**대기 시간** 감시 | **반복 축출·기아** 완화 |
| 복제본의 노드 집중으로 단일 장애 영향 확대 | **토폴로지 분산·반친밀도** 적용 | 노드·영역별 **장애 영향** 분산 |
| 자동 확장 노드의 레이블·테인트 불일치 | 노드 **템플릿·배치 조건** 동기화 | 확장 후 **미배치** 방지 |

### 쉽게 이해하기 (학습용)
- GPU 파드에 필수 레이블을 요구했다면 노드 자동 확장 템플릿에도 같은 레이블과 자원 정보가 있어야 새 노드가 생긴 뒤 배치된다.

## Ⅶ. 결론

- 자원·**필수 조건**은 필터, **장애 분산**은 점수, 용량 부족은 노드 확장으로 처리

### 쉽게 이해하기 (학습용)
- 실행 불가능 조건은 필터에만 두고 장애 분산 같은 선호는 점수로 표현해야 가용 후보를 유지하면서 배치 품질을 높일 수 있다.
