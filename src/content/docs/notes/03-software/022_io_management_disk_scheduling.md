## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Disk Scheduling(디스크 스케줄링)**: 보조기억장치의 기계적 헤드 이동 거리를 최소화하기 위해 I/O 요청 큐의 처리 순서를 재정렬(Sorting)하고 인접 블록을 병합(Merging)하는 운영체제 I/O 최적화 기법.
- **Seek Time(탐색 시간)**: 하드디스크 드라이브(HDD)에서 읽기/쓰기 헤드가 대상 데이터가 위치한 실린더(트랙)로 물리적으로 이동하는 데 소요되는 시간.

</details>

- 정의/개념: 저장 매체의 물리적 접근 특성에 맞추어 I/O 요청 큐를 재정렬(Sorting) 및 병합(Merging)함으로써 탐색 지연(Seek Time)을 최소화하고 I/O 처리량(Throughput)을 극대화하는 **블록 계층 I/O 스케줄링** 메커니즘
- 배경/필요성: 무작위 I/O 요청 인입 시 헤드의 잦은 왕복 이동으로 인한 **탐색 시간 폭증 및 I/O 병목에 따른 전체 시스템 성능 저하 방지** 필요

#### 한줄 요약

- I/O 요청을 병합 및 재정렬하여 탐색 지연을 줄이고 스토리지 미디어 특성(HDD vs NVMe SSD)에 부합하는 처리량을 확보하는 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Rotational Latency(회전 지연시간)**: 헤드가 목표 트랙에 도달한 후, 플래터가 회전하여 원하는 섹터가 헤드 아래로 올 때까지 대기하는 시간.
- **blk-mq(Multi-Queue Block I/O)**: 다중 코어 환경에서 CPU 코어별 소프트웨어 큐와 스토리지 컨트롤러의 하드웨어 큐를 매핑하여 수백만 IOPS의 병렬 I/O를 지원하는 리눅스 커널 블록 레이어.

</details>

- HDD의 주요 물리적 지연 요인인 **탐색 시간(Seek Time) 및 회전 지연(Rotational Latency) 최소화**
- 인접 블록 요청을 단일 대형 요청으로 묶는 **요청 병합(Merging)** 및 진행 방향 기반 **정렬(Sorting)**
- 기계적 헤드가 없는 플래시 미디어(NVMe SSD) 환경에서는 헤드 스케줄링 대신 **다중 큐(blk-mq)** 기반 병렬 처리 극대화

#### 한줄 요약

- **헤드 이동 거리 최소화·인접 요청 병합·SSD 환경 멀티 큐(blk-mq) 기반 병렬 확장성 제공** ## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Elevator Algorithm(엘리베이터 알고리즘, SCAN)**: 엘리베이터의 운행 방식과 유사하게 헤드가 한쪽 방향으로 이동하면서 경로상의 모든 요청을 순차 처리하고, 끝단에 도달하면 방향을 전환하는 기본 디스크 스케줄링 기법.

</details>

```text
[ 블록 I/O 계층 및 디스크 스케줄러 구조 ]
          [ 사용자 응용 프로그램 (Application) ]
                            │
               [ 가상 파일 시스템 (VFS) ]
                            │
              [ 블록 I/O 계층 (BIO Layer) ]
                            │
    ┌───────────────────────┴───────────────────────┐
    ▼ (단일 큐/전통 HDD)                             ▼ (멀티 큐/NVMe SSD)
 [ I/O 요청 큐 (Request Queue) ]          [ 소프트웨어 스테이징 큐 (코어별) ]
    ├─ 병합기 (Request Merging)                      │
    └─ 엘리베이터 정렬기 (SCAN, C-LOOK)     [ 하드웨어 디스패치 큐 (Submission) ]
                            │                        │
                            └───────────┬────────────┘
                                        ▼
                             [ 디바이스 드라이버 ]
                                        │
                             [ 물리 디스크 (HDD / SSD) ]
                                        │
                             [ 인터럽트 핸들러 (IRQ) ]
```

선의 의미: VFS에서 전달된 블록 I/O 요청을 디스크 스케줄러가 병합/정렬하여 디바이스 드라이버에 디스패치하고, 하드웨어 완료 인터럽트를 통해 프로세스를 깨우는 구조.

| 구성요소 | 책임 |
|:---|:---|
| I/O 요청 큐 | 블록 계층에 인입된 I/O 요청을 저장하고 스케줄러 알고리즘에 따라 재배치하는 버퍼 |
| I/O 스케줄러 | 헤드 이동 동선 최소화(HDD) 또는 타깃 지연시간 보장(SSD)을 위한 스케줄링 알고리즘 수행 |
| 블록 병합기(Merging) | 연속된 물리 LBA 주소를 갖는 복수의 I/O 요청을 단일 트랜잭션으로 통합 |
| 디바이스 드라이버 | 표준 블록 명령어를 SATA/SCSI/NVMe 프로토콜 명령어로 변환하여 컨트롤러에 전달 |
| 인터럽트 핸들러 (IRQ) | 하드웨어 I/O 완료 신호를 수신하여 페이지 캐시를 갱신하고 대기 프로세스 복귀(Wakeup) |

#### 한줄 요약

- **블록 요청 큐·스케줄링 알고리즘(엘리베이터/blk-mq)·블록 병합기·디바이스 드라이버 및 인터럽트 처리기** 

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Request Merging & Sorting(요청 병합 및 정렬)**: 인접한 섹터로 향하는 요청을 하나로 묶어 디스크 컨트롤러 오버헤드를 줄이고, 헤드 이동 경로 순서대로 정렬하여 탐색 시간을 단축하는 과정.

</details>

```text
[ 디스크 I/O 요청 처리 및 스케줄링 시퀀스 ]
 1. 블록 I/O 요청 생성 (submit_bio)
          │
          ▼
 2. 인접 블록 여부 확인 및 요청 병합(Merging)
          │
          ▼
 3. 스케줄링 정책에 따른 요청 큐 정렬(Sorting)
          │
          ▼
 4. 디바이스 드라이버 디스패치 (Submission Queue)
          │
          ▼
 5. 물리 스토리지 컨트롤러 명령 실행 및 인터럽트(Completion) 발생
          │
          ▼
 6. I/O 완료 통지 및 대기(Blocked) 프로세스 상태를 Ready로 전환
```

**동작 원리** 1. **요청 인입 및 병합**: 파일 시스템 계층에서 넘어온 BIO 구조체를 분석하여 기존 큐에 인접한 블록이 존재할 경우 병합(Front/Back Merge) 수행
2. **정렬 및 큐 삽입**: 활성화된 I/O 스케줄러(C-LOOK, BFQ 등)의 기준에 따라 트랙 위치별로 요청을 정렬 삽입
3. **디바이스 디스패치**: 드라이버가 최적화된 순서로 요청을 꺼내 하드웨어 Submission Queue에 투입
4. **물리 실행 및 인터럽트**: HDD 헤드 이동/플래터 회전 또는 SSD 플래시 쓰기를 수행한 후 하드웨어 인터럽트 발생
5. **완료 처리**: 커널이 I/O 완료를 확인하고 데이터를 사용자 버퍼에 매핑한 뒤 대기 프로세스를 실행 대기열로 복귀

#### 한줄 요약

- **BIO 인입 $\to$ 요청 병합(Merge) $\to$ 스케줄링 정렬(Sort) $\to$ 디스패치 $\to$ 완료 인터럽트 및 프로세스 재개** 

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SSTF(Shortest Seek Time First)**: 현재 헤드 위치에서 가장 이동 거리가 짧은 요청을 우선 처리하는 탐욕적(Greedy) 방식으로, 양 끝단 요청에 대한 기아(Starvation) 위험 내포.
- **C-LOOK(Circular LOOK)**: 헤드가 한 방향으로만 이동하며 요청을 처리하고, 끝단에 도달하면 즉시 시작 트랙으로 이동하여 단방향 스캔을 반복하는 가장 실용적인 HDD 스케줄러.

</details>

| 스케줄링 알고리즘 | 동작 방식 | 장단점 및 특성 | 주 적용 환경 |
|:---|:---|:---|:---|
| **FCFS (First-Come First-Served)** | 요청 도착 순서대로 처리 | 구현이 단순하나 탐색 시간 최악, 헤드 무작위 왕복 | 단순 임베디드 장치 |
| **SSTF** | 현재 헤드에서 최소 탐색 거리 우선 처리 | 평균 탐색 시간 단축, 그러나 양 끝단 트랙의 **기아 현상(Starvation)** 유발 | 탐색 거리 최적화 기초 모델 |
| **SCAN / LOOK** | 양방향 엘리베이터 스캔 (LOOK은 요청 없으면 턴) | 기아 현상 방지, 그러나 방향 전환 시 중앙 트랙 편향 발생 | 일반 레거시 HDD |
| **C-SCAN / C-LOOK** | 단방향 스캔 및 반대편 시작점 즉시 복귀 | **대기시간의 균일성(Uniformity) 확보**, 실질적 HDD 최적 표준 | 엔터프라이즈 HDD 스토리지 |
| **none / mq-deadline** | 정렬 없이 FIFO 전달 또는 마감시간 보장 | CPU 오버헤드 극소화, **수십만 IOPS 병렬 처리 지원** | **NVMe / SATA SSD** |

#### 한줄 요약

- HDD 환경의 균일 응답은 **C-LOOK**, 플래시/NVMe 초고속 병렬 환경은 **none / mq-deadline** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **mq-deadline vs BFQ**: 리눅스 커널 블록 I/O 스케줄러 옵션으로, 대기시간 상한을 보장하는 고성능 SSD용 `mq-deadline`과 프로세스 간 공정 대역폭을 보장하는 복합 워크로드용 `bfq`.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 초고속 NVMe SSD에 HDD용 복잡한 스케줄러 적용 시 **CPU 오버헤드 및 락 경합 발생** | I/O 스케줄러를 **`none`(No-op)** 또는 **`mq-deadline`** 으로 설정 | 불필요한 정렬 연산 제거 및 초저지연 병렬 성능 극대화 |
| 대용량 순차 쓰기 작업이 집중되어 **대화형 읽기(Read) 요청 지연 발생** | 읽기 큐의 우선순위를 상향하고 쓰기 지연 상한을 강제하는 **`mq-deadline` 튜닝** | 읽기 응답 지연(Tail Latency) 감소 및 사용자 체감 성능 보장 |
| HDD 환경에서 특정 프로세스의 연속 I/O로 인한 **타 프로세스 I/O 기아 현상** | 프로세스별 I/O 가중치를 공정 분배하는 **`bfq`(Budget Fair Queueing)** 적용 | 프로세스 간 I/O 대역폭 공정성 및 안정성 확보 |

#### 한줄 요약

- **NVMe 환경 none/mq-deadline 적용·읽기 우선순위 보장·HDD 환경 BFQ 공정 분배** 

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Storage-Aware I/O Scheduler Selection**: 저장 매체의 물리적 구조(기계식 회전체 vs 반도체 플래시)와 워크로드 패턴에 맞춰 최적의 I/O 스케줄러를 구성하는 엔지니어링 기준.

</details>

- 회전형 하드디스크(HDD) 환경은 **C-LOOK/BFQ**, 탐색 지연이 없는 SSD 및 클라우드 가상 디스크 환경은 **`none` 또는 `mq-deadline`** 채택 표준화

#### 한줄 요약

- **스토리지 미디어의 물리 특성에 부합하는 I/O 스케줄러 선택** 통한 시스템 I/O 병목 제거 및 응답성 극대화
