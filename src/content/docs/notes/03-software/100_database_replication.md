## 미리 알고가기

- **데이터베이스 복제(Database Replication)**: 한 데이터베이스의 변경을 다른 노드에 반영해 사본을 유지하는 기술임
- **주 노드(Primary Node)**: 단일 주 노드 복제에서 쓰기를 받아 변경 순서를 확정하는 노드임
- **복제 노드(Replica Node)**: 주 노드의 변경 로그를 적용해 데이터 사본을 유지하는 노드임
- **동기 복제(Synchronous Replication)**: 필요한 복제 노드의 반영 확인을 받은 뒤 쓰기 성공을 반환하는 방식임
- **비동기 복제(Asynchronous Replication)**: 주 노드가 먼저 쓰기 성공을 반환하고 이후 복제 노드가 변경을 따라가는 방식임
- **장애 조치(Failover)**: 주 노드 장애 시 적합한 복제 노드를 승격해 서비스를 이어 가는 절차임
- **분할 뇌(Split Brain)**: 둘 이상의 노드가 동시에 주 노드 역할을 수행해 데이터가 분기되는 장애 상태임
- **정족수(Quorum)**: 분산 노드의 결정을 유효하게 만들기 위해 필요한 최소 동의 수임
- **복구 시간 목표(Recovery Time Objective, RTO)**: 장애 뒤 서비스를 복구해야 하는 목표 시간임
- **복구 시점 목표(Recovery Point Objective, RPO)**: 장애 시 허용할 수 있는 최대 데이터 손실 시간 범위임

## Ⅰ. 개요

- 정의/개념: 변경 로그로 여러 노드의 사본을 유지함
- **배경/필요성**: 읽기 부하·노드 장애로 데이터 복제 필요

### 쉽게 이해하기 (학습용)
- 원본 장부의 변경 내용을 여러 지점 장부에 전달해 같은 사본을 유지하는 방식임

## Ⅱ. 특징

- 읽기 부하를 여러 복제본으로 나눠 처리량을 높인다.
- 다른 노드를 승격해 장애 복구 시간을 줄인다.
- 비동기는 응답을 앞당기지만 복제 지연을 만든다.
- 다중 주 노드는 쓰기 가용성과 충돌·분기를 함께 늘린다.

### 쉽게 이해하기 (학습용)
- 읽기와 장애 대응은 좋아지지만 사본 반영 지연과 두 원본 충돌을 관리해야 함

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 변경 로그 | 어떤 순서로 변경이 일어났는지 기록해 복제의 기준이 됨 |
| 복제 반영 엔진 | 로그를 읽어 복제본에 변경을 적용함 |
| 지연 감시 | 원본과 복제본의 차이를 측정해 읽기 신뢰도를 판단함 |
| 장애 조치 정책 | 승격 대상과 전환 순서 및 분기 방지 규칙을 정함 |

```text
  쓰기요청
      ↓
  로그기록
      ↓
  반영엔진
      ↓
  사본갱신
```

> 요약: 로그·지연·조치로 복제 가용성 통제

### 쉽게 이해하기 (학습용)
- 변경 일지, 사본 반영기, 지연 계기판과 원본 교체 규칙으로 구성됨

## Ⅳ. 원리 및 절차 흐름도

```text
  변경확정
      ↓
  로그전달
      ↓
  순서재생
      ↓
  전환관리
```

| 절차 | 설명 |
|:---|:---|
| **원본 변경 확정** | 주 노드가 커밋하고 변경 로그를 생성함 |
| **로그 전달** | 동기와 비동기 정책에 따라 로그를 전송함 |
| **복제본 반영** | 로그 순서에 따라 변경을 재생해 사본을 갱신함 |
| **지연·장애 전환 관리** | 지연을 감시하고 장애 시 정족수를 확인해 복제본을 승격함 |

> 요약: 주 노드 로그 재생·지연·장애 전환 관리

### 쉽게 이해하기 (학습용)
- 변경 일지를 사본에 적용하고 얼마나 늦게 따라오는지 측정함

## Ⅴ. 종류 및 비교

| 판단 기준 | 단일 주 노드 복제 | 다중 주 노드 복제 |
|:---|:---|:---|
| 핵심 특징 | 한 노드만 쓰기를 받음 | 여러 노드가 쓰기를 받음 |
| 쓰기 충돌 | 단일 주 노드가 쓰기 순서를 결정함 | 동시 쓰기를 감지해 병합하거나 거부함 |
| 적용 기준 | 읽기 분산과 단순한 전환이 필요한 곳에 씀 | 쓰기 수용과 충돌 해결이 가능한 곳에 씀 |
| 주요 위험 | 주 노드 장애·복제 지연 | 쓰기 충돌·병합 오류 |

> 요약: 순서 단순화와 충돌 처리 비교

### 쉽게 이해하기 (학습용)
- 한 곳은 순서가 단순하고 여러 곳은 지역 쓰기가 빠르나 충돌 규칙이 필요함

## Ⅵ. 실무 사례

1. 조회 시스템은 비동기 복제본으로 분산하고 복제 지연을 확인함
2. 결제 시스템은 자동 장애 조치를 적용하고 전환 시간을 확인함

### 쉽게 이해하기 (학습용)
- 비동기 읽기 복제본은 부하를 줄이지만 최신 변경이 늦게 보일 수 있어 허용 지연을 감시해야 함
- 자동 장애 조치는 승격 시간뿐 아니라 마지막 로그 누락과 이중 주 노드 방지를 장애 훈련으로 검증해야 함

## Ⅶ. 결론

- 지연·RPO·RTO·분기 방지 기준으로 복제 운영

### 쉽게 이해하기 (학습용)
- 복제는 사본 수를 늘리는 기술이 아니라 지연·손실·승격·충돌을 정해 둔 기준으로 통제할 때 가용성을 높임
