## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소프트웨어 공급망 보안 (Software Supply Chain Security)**: 소스코드 작성, 의존성 라이브러리 반입, 빌드 환경, 패키징, 배포에 이르는 SDLC 전 과정에서 악성코드 삽입 및 무단 변조를 차단하고 암호학적으로 무결성을 검증하는 보안 프레임워크.
- **공급망 침해 및 신뢰 경로 공격(Software Supply Chain Attack)**: SolarWinds 사태처럼 소스코드나 빌드 서버를 장악하여 정상적인 소프트웨어 업데이트 경로를 통해 백도어를 전파하는 지능형 위협.

</details>

- 정의/개념: 소스코드 작성, 빌드, 패키징, 배포에 이르는 **SDLC 전 주기의 산출물 무결성과 출처를 암호학적으로 검증**하는 소프트웨어 공급망 보안 체계
- 배경/필요성: SolarWinds 사태 및 오픈소스 의존성 오염으로 인한 **빌드 파이프라인 악성코드 삽입 및 신뢰 업데이트 경로 침해 위험** 직면

#### 한줄 요약

- 소스코드부터 배포 파드까지 SLSA 프레임워크와 전자서명을 기반으로 종단 간(E2E) 무결성 신뢰 체인을 구축

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **SLSA (Supply-chain Levels for Software Artifacts)**: 구글이 제안한 소프트웨어 공급망 무결성 표준(Level 1~4)으로 빌드 프로세스의 위변조 방어 수준을 정량 평가하는 프레임워크.
- **출처 증명(Provenance)**: 산출물이 어떤 소스코드 커밋에서, 어떤 빌드 환경을 거쳐 생성되었는지를 암호학적으로 서명하여 증명하는 메타데이터.

</details>

- 빌드 환경을 인터넷과 격리하고 일회성으로 구동하는 **격리된 빌드(Hermetic & Ephemeral Build)**
- 빌드 산출물과 소스 커밋 간의 1:1 일치성을 보증하는 **출처 증명(Provenance) 및 전자서명**
- 배포 직전 컨테이너 이미지의 서명과 SBOM을 강제 검증하는 **쿠버네티스 정책 게이트(Admission Controller)** #### 한줄 요약

- 소스 통제, 격리 빌드, 증적 서명, 정책 게이트 검증을 통해 공급망 공격을 원천 차단

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **공급망 보안 4대 신뢰 계층**: Source Control(소스 거버넌스), Trusted Builder(격리 빌더), Attestation Store(서명/증적 저장소), Policy Gate(배포 검문소).

</details>

```text
[ 소프트웨어 공급망 보안(SLSA 기반) 신뢰 체인 구조도 ]

 1. [ 소스코드 계층 (Source Control: Git) ] ── (2인 승인 및 GPG 커밋 서명)
                           │
                           ▼
 2. [ 격리 빌드 계층 (Trusted Ephemeral Builder) ] ──────────────┐
    • 네트워크 격리(Hermetic), 의존성 해시 고정(Lock), 빌드 실행  │
    └──────────────────────┬──────────────────────────────────────┘
                           │ (산출물 및 증적 생성)
                           ▼
 3. [ 증적 및 서명 계층 (Attestation: Cosign / Rekor) ] ────────┐
    • 컨테이너 이미지 SHA-256 Digest 결속                        │
    • SBOM (CycloneDX) + SLSA Provenance 생성 및 Keyless 서명    │
    └──────────────────────┬──────────────────────────────────────┘
                           │
                           ▼
 4. [ 배포 검문 계층 (Policy Gate: Kyverno / OPA Gatekeeper) ]
    • K8s Admission Control: 서명 검증 ➔ 승인된 이미지만 Pod 실행
```

선의 의미: 소스 검증에서 격리 빌드를 거쳐 생성된 이미지와 증적을 저장하고, K8s 정책 게이트가 서명을 검증하여 실행을 허가하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 소스 제어 계층 (Source) | Branch Protection, 2인 이상 코드 리뷰, **GPG 커밋 서명으로 비인가 코드 유입 차단** |
| 신뢰 빌더 (Trusted Builder) | 일회성(Ephemeral) 격리 컨테이너에서 **해시 고정된 불변 입력만으로 빌드 수행** |
| 증적 저장소 (Attestation) | 이미지 Digest에 결속된 **SBOM 및 SLSA Provenance를 생성하고 Sigstore 서명 보관** |
| 정책 게이트 (Policy Gate) | K8s Admission Controller를 통해 **서명과 출처가 검증된 이미지만 클러스터 배포 허용** |

#### 한줄 요약

- 소스 제어, 신뢰 빌더, 증적 서명, 정책 게이트가 유기적으로 결합하여 공급망 무결성을 사수

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **공급망 보안 5단계 파이프라인**: 불변 입력 고정 $\to$ 격리 빌드 $\to$ 증적 생성 및 서명 $\to$ 레지스트리 보관 $\to$ 정책 게이트 검증 배포.

</details>

```text
[ SLSA 기반 공급망 보안 파이프라인 처리 흐름도 ]

 ┌────────────────────────────────────────┐
 │ 1. 소스 커밋 서명 및 의존성 해시 락 고정
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 네트워크 격리된 Ephemeral CI 빌드 실행│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. SBOM 추출 및 Cosign 출처 증명 서명 결속
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 서명된 이미지 및 증적 레지스트리 보관│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. K8s Kyverno 정책 게이트 서명 검증 후 배포
 └────────────────────────────────────────┘
```

### 동작 원리

1. 입력 고정: 개발자가 GPG 서명으로 커밋하고 `package-lock.json`의 SHA-512 해시로 외부 모듈을 동결.
2. 격리 빌드: GitHub Actions가 일회성 러너(Runner)를 생성하여 외부 인터넷을 차단한 상태에서 바이너리를 컴파일.
3. 증적 결속: Syft로 SBOM을 생성하고 Cosign으로 이미지 다이제스트와 출처(Provenance)에 암호학적 서명을 날인.
4. 불변 보관: Harbor 레지스트리에 컨테이너 이미지와 서명 메타데이터를 불변(Immutable) 태그로 저장.
5. 게이트 검증: 쿠버네티스 Kyverno 컨트롤러가 배포 요청을 가로채어 Sigstore 서명이 확인된 경우에만 파드 기동을 승인.

#### 한줄 요약

- 입력 고정 $\to$ 격리 빌드 $\to$ 증적 서명 $\to$ 레지스트리 보관 $\to$ 게이트 검증의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **예방적 통제 vs 탐지적 통제**: 빌드 중 악성코드 유입을 원천 차단하는 방식(Prevention)과 배포 전 서명/스캔으로 결함을 걸러내는 방식(Detection).

</details>

| 구분 | 예방적 통제 (Prevention) | 탐지 및 차단 통제 (Detection & Enforcement) |
|:---|:---|:---|
| **적용 기준** | 소스코드 작성 및 CI 빌드 파이프라인 내부 | 컨테이너 레지스트리 보관 및 K8s 클러스터 배포 시점 |
| **핵심 특징** | **GPG 커밋 서명, 의존성 Lock 고정, 격리(Hermetic) 빌드** | **SBOM 생성, 취약점 스캔(Trivy), K8s 정책 게이트(Kyverno)** |
| **한계** | 개발자의 키 관리 및 빌드 환경 격리 구성의 난이도 | 이미 생성된 악성 산출물을 사후에 걸러내야 하는 한계 |

#### 한줄 요약

- 빌드 전 과정은 예방적 격리 통제, 배포 시점은 탐지적 정책 게이트 통제를 병행 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **의존성 혼동(Dependency Confusion)**: 사내 전용 프라이빗 패키지와 동일한 이름으로 공개 저장소(npm)에 악성 패키지를 배포하여 내부 시스템으로 유입시키는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 의존성 혼동 공격으로 내부 빌드 시 악성 공개 패키지 다운로드 | **사내 Nexus 레지스트리 스코프 우선순위 강제 및 해시 락 고정** | 악성 패키지 혼입 원천 차단 |
| CI 서버 자격 증명(AWS Secret) 탈취로 인한 공급망 오염 | **단기 OIDC 토큰 기반 Keyless 인증 및 일회성 러너 도입** | 정적 크리덴셜 유출 위험 제로화 |
| 테스트되지 않은 무서명 컨테이너 이미지가 운영 K8s에 배포됨 | **쿠버네티스 `Kyverno / OPA Gatekeeper` 서명 검증 의무화** | 비인가 이미지 배포 100% 차단 |

#### 한줄 요약

- 의존성 해시 고정, OIDC Keyless 서명, K8s Admission Control을 통해 공급망 보안을 완성

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **엔드-투-엔드 공급망 신뢰 체인(E2E Supply Chain Trust)**: 소스코드 한 줄부터 프로덕션 컨테이너 런타임까지 단 1%의 변조도 허용하지 않는 현대 보안의 필수 요구조건.

</details>

- **소프트웨어 공급망 보안** 현대 클라우드 네이티브 환경의 핵심 방어선이며, SLSA 프레임워크를 기반으로 소스 검증, 격리 빌드, SBOM 생성, Cosign 전자서명 및 정책 게이트를 전사 파이프라인에 체계화해야 함

#### 한줄 요약

- SLSA 프레임워크와 전자서명 신뢰 체인을 통해 소스부터 배포까지 완벽한 공급망 무결성을 완성
