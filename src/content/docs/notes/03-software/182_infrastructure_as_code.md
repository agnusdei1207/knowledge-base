## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **Plan**: Plan은 코드, 상태 장부, 실제 인프라를 비교해 생성•변경•교체•삭제 대상을 계산한 결과다.
- **코드형 인프라(Infrastructure as Code, IaC)**: 인프라 목표 상태를 버전 관리 가능한 코드로 선언하고 계획 검토와 자동 적용으로 환경을 구성하는 방식이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: IaC 엔진이 플랫폼 자원을 조회•변경하는 접점이다.

</details>

- 정의/개념: 목표 상태 코드와 Plan 기반 **IaC 구성 관리 방식**이다.
- 배경/필요성: 수동 구축은 절차 누락•**환경 편차**로 재현성 제약이 발생한다.

#### 한줄 요약

- 서버 설치 설명서를 실행 코드로 만들고 실제 변경 전 생성•교체•삭제 목록을 검토해 같은 환경을 반복 재현한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **계획(Plan)**: 생성•수정•교체•삭제할 자원을 계산한 결과이다.
- **정책 검사**: 계획이 보안•운영 기준을 위반하는지 확인하는 통제이다.
- **계획 승인**: 실제 적용 전에 변경 대상을 책임자가 허가하는 통제이다.
- **상태(State)**: IaC 코드와 실제 자원의 매핑을 관리하는 장부이다.
- **편차(Drift) 탐지**: 목표 상태와 실제 상태의 차이를 찾는 기능이다.

</details>

- **모듈•변수•버전** 기반 환경 재현이 핵심이다.
- **Plan•정책 검사•승인** 기반 변경을 통제한다.
- **상태•Drift 탐지** 기반 목표 수렴이 핵심이다.

#### 한줄 요약

- 코드만 저장하는 것이 아니라 실제 자원과 연결한 상태 장부를 함께 관리해야 수동 변경과 삭제 영향을 계획에서 찾을 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **원격 상태 저장소**: 원격 상태 저장소는 자원 매핑을 버전 관리하고 암호화하며 동시 적용을 잠금으로 통제한다.
- **IaC 엔진**: 의존성 그래프로 자원 변경 순서를 정하는 구성요소이다.
- **공급자(Provider)**: IaC 선언을 플랫폼 API 호출로 변환하는 구성요소이다.
- **검증 파이프라인**: 코드 형식•보안•정책과 변경 계획을 검사•승인하는 구성요소이다.
- **편차 탐지**: 수동 변경을 찾아 코드 반영 또는 실제 자원 원복 대상으로 분류하는 구성요소이다.

</details>

```text
IaC 구성 구조
      |
      +-- 코드•검증
      |         +-- [코드 저장소]
      |         +-- [검증 파이프라인]
      |
      +-- 실행•상태
      |         +-- [IaC Engine•Provider]
      |         +-- [원격 상태 저장소]
      |
      +-- 관찰•수렴
                +-- [편차 탐지]
```

| 구성요소 | 책임 |
|:---|:---|
| 코드 저장소 | 자원•모듈•**변수•버전 이력** |
| 검증 파이프라인 | 형식•보안•**정책•Plan 검토** |
| IaC Engine•Provider | **Provider•의존성 그래프** 기반 플랫폼 API 변환 |
| 원격 상태 저장소 | 자원 매핑•**버전•암호화•잠금** |
| 편차 탐지 | 실제 차이•**코드 반영•원복 분류** |

#### 한줄 요약

- 저장소가 설계도, 파이프라인이 검사소, 엔진이 시공자, 원격 상태가 실제 건물과 설계도를 연결하는 장부 역할을 한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 상태 잠금•조회**: 공유 상태를 잠그고 자원 매핑을 읽는 단계이다.
- **2. 실제 상태 조회**: 플랫폼 자원의 현재 속성을 수집하는 단계이다.
- **3. Plan 생성•승인**: 코드•상태•실제 자원의 차이를 검토하는 단계이다.
- **4. 승인 변경 적용**: 허가된 생성•변경•교체•삭제만 실행하는 단계이다.
- **5. 상태 갱신•잠금 해제**: 적용 결과를 기록하고 동시 변경 통제를 끝내는 단계이다.

</details>

```text
인프라 코드 변경
      |
      v
1. 상태 잠금•조회
      |
      v
2. 실제 상태 조회
      |
      v
3. Plan 생성•승인
      |
      +-- 승인 거부 --> 잠금 해제•변경 없음
      |
      +-- 승인 완료
              |
              v
4. 승인 변경 적용
      |
      +-- 적용 실패 --> 실제 상태 재조회•복구 판단
      |
      +-- 적용 성공
              |
              v
5. 상태 갱신•잠금 해제
              |
              v
          적용 결과 반환
```

**동작 원리**

1. **상태 잠금•조회**: 동시 적용 차단•자원 매핑을 확인한다.
2. **실제 상태 조회**: 코드•상태와 비교할 플랫폼 자원을 수집한다.
3. **Plan 생성•승인**: 변경 대상과 정책 위반을 검토한다.
4. **승인 변경 적용**: 허가된 생성•변경•교체•삭제를 실행한다.
5. **상태 갱신•잠금 해제**: 새 자원 매핑 기록•통제를 종료한다.

#### 한줄 요약

- 검토한 Plan과 같은 변경만 적용하고 실행 동안 상태를 잠가 두 사람이 같은 자원을 동시에 만들거나 덮어쓰지 않게 한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **선언형 IaC(Declarative IaC)**: 목표 상태를 기술하고 엔진이 현재 상태와의 차이를 계산하는 방식이다.
- **명령형 IaC(Imperative IaC)**: 자원 생성 명령•조건•실행 순서를 직접 기술하는 방식이다.

</details>

| IaC 방식 | 선언형 | 명령형 |
|:---|:---|:---|
| 적용 기준 | 반복 환경•**목표 상태 수렴** | 일회 절차•**세밀한 순서 제어** |
| 핵심 특징 | 현재 차이•**Plan•Drift 계산** | 명령•조건•**실행 순서 명시** |
| 한계 | 상태•Provider **동작 의존** | 재실행 부작용•**절차 누락** |

#### 한줄 요약

- 선언형은 완성 모습을 적어 엔진이 차이를 맞추고 명령형은 만드는 순서를 직접 적어 각 단계의 재실행 안전성까지 작성자가 책임진다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **상태 덮어쓰기**: 상태 덮어쓰기는 여러 실행이 공유 상태를 동시에 갱신해 자원 매핑과 실제 인프라가 어긋나는 문제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 상태의 **비밀•식별자 노출** | 암호화•최소 권한•**비밀 분리** | **상태 정보** 노출 방지 |
| 동시 적용의 **상태 덮어쓰기** | 원격 잠금•**단일 배포 경로** | **중복 자원** 생성 방지 |
| 검토 뒤 **Plan 변경** | 저장 Plan•**짧은 승인 구간** | **승인 대상** 일치 |
| 삭제•교체의 **데이터 손실** | 삭제 보호•백업•**별도 승인** | **파괴적 변경** 차단 |
| 긴급 수동 변경의 **편차 잔존** | 주기 탐지•**코드 반영•원복** | 코드•**실제 상태** 수렴 |

#### 한줄 요약

- 운영에서 긴급 변경했다면 다음 Plan이 되돌릴 수 있으므로 예외를 코드에 반영하거나 실제 자원을 원복하는 결정을 즉시 남겨야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **저장 Plan**: 검토•승인한 대상과 실제 적용 대상을 일치시키려면 생성 시점의 저장 Plan만 적용해야 한다.

</details>

- 삭제 영향•상태 복구성을 확인해 **저장 Plan**만 적용하고 편차는 코드 반영•원복이 핵심이다.

#### 한줄 요약

- 저장된 Plan만 승인해 적용하고 원격 상태 잠금•삭제 보호•편차 복구를 갖춰야 IaC가 단순 자동화가 아닌 변경 통제가 된다.
