## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플랫폼 엔지니어링 셀프서비스(Platform Engineering Self-Service)**: 개발팀의 인지 부하(Cognitive Load)를 줄이고 배포 속도를 높이기 위해, 내부 개발자 플랫폼(IDP: Internal Developer Platform)을 통해 사전 검증된 인프라 및 CI/CD 템플릿(골든 패스: Golden Path)과 정책 가드레일을 셀프서비스 형태로 제공하는 엔지니어링 패러다임.
- **수동 티켓팅 및 인프라 운영 병목 위험(Manual Ticket Queue & Bottleneck Risk)**: 개발자가 서버나 DB를 발급받기 위해 인프라팀에 티켓을 요청하고 수일간 승인을 대기함으로써 배포 리드타임이 급증하고 인프라팀이 단순 반복 작업에 매몰되는 위험.

</details>

- 정의/개념: 내부 개발자 플랫폼(IDP)을 통해 **인프라와 배포 파이프라인을 셀프서비스 골든 패스(Golden Path)로 제공**하는 엔지니어링 패러다임
- 배경/필요성: 인프라팀에 대한 수동 티켓 요청 의존으로 인한 **배포 리드타임 지연, 인프라 운영 병목 및 개발자 인지 부하 가중 위험** 직면

#### 한줄 요약

- 백스테이지(Backstage) 기반 개발자 포털과 Policy-as-Code 가드레일을 결합하여 티켓 없는 안전한 셀프서비스 프로비저닝을 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **골든 패스(Golden Path / Paved Road)**: 보안 규정과 아키텍처 베스트 프랙티스가 사전에 내장되어 있어, 개발자가 별도의 인프라 고민 없이 가장 빠르고 안전하게 배포할 수 있도록 지원하는 표준 경로.
- **개발자 인지 부하 감소(Cognitive Load Reduction)**: 쿠버네티스 YAML, 네트워크 설정, 모니터링 연동 등 복잡한 인프라 상세를 골든 패스 뒤로 추상화하여 비즈니스 로직 개발에만 집중하게 하는 효과.

</details>

- 개발자가 클릭 몇 번으로 인프라와 배포 파이프라인을 즉시 발급받는 **노-티켓 셀프서비스(No-Ticket Self-Service)**
- 보안, 비용 한도, 컴플라이언스를 코드로 사전 강제하는 **Policy-as-Code 가드레일(OPA)**
- 플랫폼을 사내 '제품(Product)'으로 대하고 개발자를 고객으로 대우하는 **제품 중심 플랫폼 운영(Platform as a Product)** #### 한줄 요약

- 골든 패스 템플릿, Policy-as-Code 가드레일, 단일 개발자 포털을 통해 자율성과 거버넌스를 동시에 달성

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IDP 셀프서비스 5대 핵심 구성요소**: Developer Portal(Backstage), Golden Path Templates(표준 패키지), Control Plane Engine(Kratix/Crossplane), Policy Guardrail(OPA/Rego), Telemetry & Feedback(사용성 분석).

</details>

```text
[ 내부 개발자 플랫폼(IDP) 셀프서비스 및 가드레일 구조도 ]

 1. [ 개발자 포털 계층 (Developer Portal: Spotify Backstage) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • 서비스 카탈로그 + 골든 패스 소프트웨어 템플릿(Spring/Node)│
    │  • 원클릭 마이크로서비스 생성 및 API 문서 단일 뷰(Single View)│
    └────────────────────────────┬────────────────────────────────┘
                                 │ (셀프서비스 요청 선언)
                                 ▼
 2. [ 정책 가드레일 엔진 (Policy-as-Code Guardrail: OPA / Kyverno) ]
    • 보안 취약점 기준, 허용 리전, 클라우드 비용 상한선 즉시 자동 심사
                                 │ (정책 통과 시 자동 프로비저닝)
                                 ▼
 3. [ 플랫폼 제어 평면 (Control Plane Engine: Crossplane / Terraform) ]
    ┌────────────────────────────┴────────────────────────────┐
    ▼                                                         ▼
 4. [ 클라우드 인프라 자원 ]                 5. [ GitOps 배포 파이프라인 ]
    • K8s Namespace, RDS DB, S3 버킷           • GitHub Repo, ArgoCD 파이프라인
```

선의 의미: 개발자가 포털에서 골든 패스를 선택하면 정책 엔진이 가드레일을 심사한 후 제어 평면이 인프라와 GitOps 파이프라인을 자동 생성하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 개발자 포털 (Backstage) | 서비스 카탈로그, **골든 패스 템플릿 검색, 자원 신청 및 전사 소유권 가시성 단일 제공** |
| 골든 패스 템플릿 (Templates) | 보안, 로깅, CI/CD가 내장된 **표준 마이크로서비스 및 인프라 스캐폴딩 패키지 제공** |
| 정책 가드레일 (Policy Engine) | OPA/Rego를 통해 **신청된 자원의 보안 규정, 비용 한도, 권한 적합성을 실시간 자동 검증** |
| 플랫폼 제어 평면 (Crossplane) | 선언적 IaC를 실행하여 **K8s 클러스터, 데이터베이스, 스토리지 자원을 즉시 자동 프로비저닝** |
| 이용 피드백 분석기 | 개발자 채택률, **배포 리드타임, 마찰 지표(Friction Metric)를 수집하여 플랫폼 로드맵 개선** |

#### 한줄 요약

- 개발자 포털, 골든 패스, 정책 가드레일, 제어 평면, 피드백 분석기가 결합하여 IDP를 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **셀프서비스 프로비저닝 5단계 수명주기**: 템플릿 선택 $\to$ 선언적 파라미터 입력 $\to$ OPA 가드레일 자동 심사 $\to$ Crossplane 자원 프로비저닝 $\to$ 서비스 카탈로그 자동 등록.

</details>

```text
[ IDP 셀프서비스 자원 프로비저닝 및 등록 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 개발자: Backstage 포털에서 템플릿 선택│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. OPA: 보안/비용 Policy-as-Code 자동 검증│
 ├───────────────────┬────────────────────┤
 │ 정책 위반 (초과)  │ 정책 통과 (적합)   │
 │ • 예외 신청 안내  │ • 프로비저닝 개시  │
 └───────────────────┴────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. Crossplane/IaC로 K8s Namespace & DB 생성
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. ArgoCD 연동 배포 파이프라인 자동 구성│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 카탈로그에 서비스 엔드포인트 및 오너 등록
 └────────────────────────────────────────┘
```

### 동작 원리

1. 템플릿 선택: 개발자가 Backstage에서 'Spring Boot + PostgreSQL 마이크로서비스' 골든 패스를 선택하고 서비스명 입력.
2. 정책 검증: OPA가 DB 요청 크기(t4g.medium)와 비용이 팀 예산 한도 내임을 0.5초 만에 자동 승인.
3. 인프라 생성: Crossplane이 AWS RDS 인스턴스와 EKS 네임스페이스를 즉시 선언적으로 생성.
4. 배포 구성: GitHub 리포지토리를 생성하고 기본 헬스체크 코드와 ArgoCD 배포 파이프라인을 자동 연결.
5. 카탈로그 등록: 신규 서비스의 API 스웨거 문서와 소유자 메타데이터가 백스테이지 포털에 즉시 동기화되어 개발 착수.

#### 한줄 요약

- 템플릿 선택 $\to$ 정책 검증 $\to$ 인프라 생성 $\to$ 배포 구성 $\to$ 카탈로그 등록의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **가드레일 셀프서비스 vs 전통적 티켓팅 vs 섀도우 IT 자율**: 자동 정책 통제(셀프서비스), 수동 승인 대기(티켓팅), 무단 개발(섀도우 IT).

</details>

| 구분 | 가드레일 셀프서비스 (IDP Self-Service) | 티켓 기반 수동 발급 (Ticket-Based) | 완전 자율 방임 (Full Autonomy) |
|:---|:---|:---|:---|
| **적용 기준** | 대다수 표준 마이크로서비스 및 반복적인 인프라 프로비저닝 | 아키텍처 예외가 크거나 고도의 보안 심사가 필요한 특수 사업 | 초기 스타트업 단계, 소규모 독립 실험 프로젝트 |
| **핵심 특징** | **사전 검증된 골든 패스 + Policy-as-Code 기반 5분 내 즉시 생성** | **Jira 티켓 발행 ➔ 인프라팀 수동 검토 ➔ 며칠 뒤 자원 전달** | **개발팀이 AWS 콘솔에서 직접 자원을 수동 생성하고 관리** |
| **한계** | 초기 플랫폼 엔지니어링 구축 비용 및 표준화 공수 소요 | 긴 배포 리드타임, 인프라팀 병목, 개발자 인지 부하 폭증 | 보안 구멍 발생, 클라우드 비용 낭비, 사내 기술 파편화 |

#### 한줄 요약

- 표준 인프라는 IDP 셀프서비스, 복잡한 특수 예외는 티켓팅 심사를 결합하여 운영

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **이스케이프 해치(Escape Hatch, 예외 경로)**: 골든 패스가 지원하지 않는 특수 프레임워크나 아키텍처가 필요할 때 플랫폼을 우회하여 수동 승인을 받을 수 있는 합법적 탈출 경로.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 골든 패스의 지나친 강제로 특수 요구 개발팀의 반발 및 갈등 | **합법적 우회 승인 절차인 `이스케이프 해치(Escape Hatch)` 제공** | 표준화 거버넌스와 개발 자율성의 조화 |
| 셀프서비스 허용 후 개발자의 방치로 클라우드 유휴 비용 폭증 | **`FinOps 자동화` 연동(미사용 개발용 DB 야간 자동 셧다운)** | 클라우드 인프라 비용 30% 이상 절감 |
| 플랫폼 구축 후 개발자가 사용하지 않아 채택률(Adoption) 바닥 | **플랫폼 팀에 `전담 PM`을 배치하고 개발자 경험(DevEx) 설문 환류** | 플랫폼 자발적 채택률 90% 이상 달성 |

#### 한줄 요약

- 이스케이프 해치 마련, FinOps 비용 자동화, 제품 중심 PM 운영을 통해 플랫폼의 생명력을 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **개발자 경험(DevEx: Developer Experience)**: 개발자가 시스템 개발 과정에서 느끼는 효율성, 만족도, 마찰의 정도를 나타내는 현대 소프트웨어 조직의 핵심 경쟁력 지표.

</details>

- **플랫폼 엔지니어링 셀프서비스** 기반 DevOps의 이상을 대규모 조직에서 현실화하는 핵심 인프라 패러다임이며, 백스테이지 개발자 포털과 Policy-as-Code 가드레일을 결합하여 개발자 경험(DevEx) 향상과 전사 거버넌스를 완성해야 함

#### 한줄 요약

- 골든 패스 템플릿과 Policy-as-Code 가드레일을 통해 티켓 없는 안전한 자율 개발자 플랫폼을 완성
