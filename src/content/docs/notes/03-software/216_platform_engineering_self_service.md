## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **내부 개발자 플랫폼(Internal Developer Platform, IDP)**: 개발•배포•운영 도구를 셀프서비스로 제공한다.
- **플랫폼 엔지니어링(Platform Engineering)**: 개발팀이 일관되고 안전하게 소프트웨어를 전달하도록 내부 플랫폼을 제품처럼 설계•운영하는 활동이다.
- **셀프서비스(Self-Service)**: 승인된 정책 범위 안에서 개발팀이 운영팀의 수동 처리 없이 필요한 자원을 직접 요청•생성하는 방식이다.

</details>

- 정의/개념: **플랫폼 엔지니어링 셀프서비스**는 내부 개발자 플랫폼이 표준화된 인프라•배포•운영 기능을 개발팀이 승인 범위에서 직접 사용할 수 있게 제공하는 운영 방식이다.
- 배경/필요성: 운영팀의 수동 자원 처리로 **대기•운영 병목**이 발생한다.

#### 한줄 요약

- 개발팀이 반복 신청을 기다리지 않고 검증된 메뉴에서 필요한 환경을 직접 만들게 하는 내부 기술 서비스다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **인지 부하 감소**: 플랫폼은 공통 기술 복잡성을 골든 패스와 자동화 뒤로 숨겨 개발팀의 인지 부하 감소를 돕는다.
- **골든 패스(Golden Path)**: 조직이 검증한 도구•구성•절차를 묶어 대부분의 개발팀에 권장하는 표준 경로이다.
- **제품 중심 운영(Product-Oriented Operation)**: 개발자를 고객으로 보고 사용성•채택률•피드백으로 플랫폼을 지속 개선하는 방식이다.

</details>

- 가드레일 내부의 **개발팀 자율성**이 핵심이다.
- 공통 기술 복잡성을 추상화해 **인지 부하 감소**가 핵심이다.
- 개발자를 고객으로 보는 **제품 중심 운영**이 핵심이다.

#### 한줄 요약

- 플랫폼이 공통 작업을 자동화하되 개발팀의 선택권과 예외 경로도 제공해야 공식 경로를 사용한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **제어 평면**: 제어 평면은 개발자 요청을 받아 정책을 확인하고 실제 자원의 생성•변경•삭제 수명주기를 조정한다.
- **개발자 포털•카탈로그(Developer Portal and Catalog)**: 서비스와 표준 템플릿을 검색•요청하고 소유권•상태를 확인하는 접점이다.
- **정책 가드레일(Policy Guardrail)**: 권한•보안•비용 한도를 코드로 검사해 허용 범위 안의 요청만 자동 처리하는 통제이다.

</details>

```text
[개발자 포털•카탈로그] ----- [골든 패스] ----- [제어 평면]
                                                    /      \
                                         [정책 가드레일] [제품 피드백]
```

선의 의미: 개발자 포털•카탈로그와 골든 패스는 제어 평면의 셀프서비스 접점에 결합되고, 제어 평면 아래에는 자동 허용 범위를 정하는 정책 가드레일과 플랫폼 개선 근거를 제공하는 제품 피드백이 놓이는 정적 플랫폼 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 개발자 포털•카탈로그 | 검색•요청과 **서비스 소유권•상태** 관리 |
| 골든 패스 | 검증된 **개발•배포 구성** 제공 |
| 제어 평면 | 정책에 따른 **자원 수명주기** 조정 |
| 정책 가드레일 | **권한•보안•비용 한도** 자동 검증 |
| 제품 피드백 | 이용 데이터•의견으로 **경로 개선** |


#### 한줄 요약

- 포털에서 표준 경로를 선택하면 제어 평면이 정책을 확인해 자원을 만들고 사용 결과를 경로 개선에 반영한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **2. 정책 자동 검증**: 제어 평면은 권한, 보안, 비용 한도를 코드화한 가드레일로 요청 사양을 자동 검증한다.
- **1. 표준 사양 전달**: 포털이 선택한 골든 패스와 입력값을 제어 평면에 전달하는 단계이다.
- **3. 자원 자동 생성**: 검증을 통과한 사양대로 인프라•저장소•배포 환경을 구성하는 단계이다.
- **4. 상태 카탈로그 등록**: 생성 자원의 소유권•접속 정보•운영 상태를 카탈로그에 기록하는 단계이다.

</details>

```text
셀프서비스 요청
      |
      v
1. 표준 사양 전달
      |
      v
2. 정책 자동 검증
      |
      +-- 정책 위반 ---- 사양 수정•예외 승인
      |
      `-- 정책 통과
              |
              v
      3. 자원 자동 생성
              |
              v
      4. 상태 카탈로그 등록
              |
              v
          처리 상태
              |
              `-- 이용 데이터•의견 ---- 골든 패스 개선
```

**동작 원리**

1. **표준 사양 전달**: 골든 패스와 입력값을 제어 평면에 전달한다.
2. **정책 자동 검증**: 권한•보안•비용 한도를 판정한다.
3. **자원 자동 생성**: 승인된 규격대로 환경을 구성한다.
4. **상태 카탈로그 등록**: 소유권•접속 정보•상태를 기록한다.


#### 한줄 요약

- 개발자가 표준 구성을 선택해 요청하면 정책 검사를 통과한 환경이 자동 생성되고 그 결과와 의견이 목록에 남는다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **가드레일 셀프서비스**: 가드레일 셀프서비스는 반복•표준화 가능한 수요를 자동 정책 범위 안에서 개발팀이 직접 처리하게 한다.
- **티켓 기반 제공(Ticket-Based Provisioning)**: 개발팀의 요청을 운영팀이 건별 검토•승인•처리하는 방식이다.
- **완전 자율(Full Autonomy)**: 개발팀이 도구와 정책을 독자적으로 선택하고 운영 책임도 직접 지는 방식이다.

</details>

| 플랫폼 제공 방식 | 가드레일 셀프서비스 | 티켓 기반 제공 | 완전 자율 |
|:---|:---|:---|:---|
| 적용 기준 | 반복 수요와 **표준화 가능성** 높음 | 예외가 많고 **승인 판단** 복잡 | 팀별 요구가 **크게 상이** |
| 핵심 특징 | 자동 정책 안에서 **직접 생성** | 운영팀이 요청마다 **수동 처리** | 개발팀이 도구•정책을 **독자 선택** |
| 한계 | 플랫폼 병목•**표준 경직** | 대기 증가•**운영팀 과부하** | 중복 투자•**통제 불일치** |

> 요약: 반복 수요는 **셀프서비스**, 복잡한 예외는 **티켓 기반 제공**을 선택한다.

#### 한줄 요약

- 자주 반복되고 규칙화할 수 있으면 셀프서비스, 사람 판단이 많이 필요하면 티켓, 팀마다 조건이 크게 다르면 자율 방식을 택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **개발자 채택률**: 개발자 채택률이 낮으면 공식 플랫폼 밖의 우회 도구가 늘어나 공통 기준과 플랫폼 투자 가치가 약해진다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 플랫폼의 가용성•처리 시간•성공률이 달성해야 할 측정 기준이다.
- **마찰 지표(Friction Metric)**: 개발자가 표준 경로를 완료하는 데 필요한 대기 시간•수동 단계•실패율을 나타내는 지표이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 골든 패스의 **경직성** | 기본 경로•**확장 지점 분리** | 자율성•표준 **균형** |
| 셀프서비스의 **과도 권한** | 정책 코드•**최소 권한 적용** | 오구성 위험 **축소** |
| 플랫폼의 **소유자 부재** | 제품 책임자•**SLO•로드맵 지정** | 운영 지속성 **확보** |
| 낮은 **개발자 채택률** | 사용성 조사•**마찰 지표 개선** | 플랫폼 가치 **향상** |

#### 한줄 요약

- 새 서비스를 시작하는 팀은 포털에서 표준 구성을 선택해 저장소와 배포 환경을 한 번에 직접 만든다.



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **승인 경로**: 반복•표준 수요는 셀프서비스로 제공하고 고위험이거나 복잡한 예외에는 별도의 승인 경로를 적용한다.
- **예외 경로(Exception Path)**: 표준 가드레일로 자동 판정하기 어려운 고위험•복잡 요청을 사람이 검토하는 별도 절차이다.

</details>

- 반복•표준 수요는 **셀프서비스**, 고위험 예외는 **승인 경로**를 적용한다.

#### 한줄 요약

- 모든 요청을 자동화하지 말고 반복되는 공통 작업은 표준 경로로 만들며 복잡한 예외에는 승인 경로를 남겨야 한다.
