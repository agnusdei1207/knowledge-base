## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AIOps (Artificial Intelligence for IT Operations)**: 대규모 IT 인프라 및 애플리케이션에서 수집되는 빅데이터(메트릭, 로그, 이벤트, 토폴로지)에 머신러닝과 AI를 결합하여 이상 탐지, 사건 상관 분석, 근본 원인 분석(RCA), 자동 복구(Auto-Remediation)를 수행하는 지능형 운영 아키텍처.
- **경보 피로 및 관제 한계(Alert Fatigue & Observability Limit)**: 수천 개 마이크로서비스에서 발생하는 수만 건의 중복 알람으로 인해 관제 엔지니어가 진짜 장애 원인을 신속히 식별하지 못하는 한계.

</details>

- 정의/개념: 대규모 IT 운영 텔레메트리 데이터에 **머신러닝과 AI를 결합하여 이상 탐지, 사건 상관 분석, 자동 복구를 수행**하는 지능형 운영 아키텍처
- 배경/필요성: 마이크로서비스 및 멀티 클라우드 확산으로 인한 **알람 폭증(Alert Fatigue), 장애 원인 규명 지연 및 수동 운영 관제 한계** 직면

#### 한줄 요약

- 머신러닝 기반의 동적 베이스라인 이상 탐지와 사건 상관 분석을 통해 수천 건의 알람 노이즈를 단일 인시던트로 압축하고 자동 복구를 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **동적 베이스라인 이상 탐지(Dynamic Baseline Anomaly Detection)**: 고정된 임계치(CPU 80%)가 아니라 요일별/시간대별 과거 트래픽 패턴을 학습하여 비정상 패턴을 선제적으로 감지.
- **사건 상관 분석(Event Correlation)**: 서로 다른 서버와 DB에서 쏟아지는 수백 개의 에러 이벤트를 시간과 토폴로지 인과관계를 기반으로 1개의 근본 장애 인시던트로 군집화.

</details>

- 고정 임계치의 한계를 넘어 시계열 패턴을 학습하는 **동적 베이스라인 기반 이상 탐지**
- 중복·연쇄 알람을 단 1개의 인시던트로 압축하는 **사건 상관 분석 및 노이즈 제거(90%↓)**
- 토폴로지 그래프 기반의 **근본 원인 분석(RCA) 및 런북 기반 자율 복구(Auto-Remediation)** #### 한줄 요약

- 수집, 가공, ML 분석, 자동 조치 파이프라인을 통해 IT 운영의 사후 대응을 사전 예방 및 자율 복구로 전환

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AIOps 4대 계층 아키텍처**: Data Ingestion(수집), Data Processing(정규화), ML Analytics Engine(이상 탐지/RCA), Action Automation(자동 런북/티켓).

</details>

```text
[ AIOps 지능형 IT 운영 플랫폼 계층 아키텍처 ]

 1. [ 데이터 수집 계층 (Data Ingestion) ]
    • Metrics (Prometheus) / Logs (Loki) / Traces (Tempo) / K8s Topology / Events
                                    │
                                    ▼
 2. [ 데이터 전처리 및 정규화 계층 (Data Processing) ]
    • 시계열 데이터 정렬, 로그 JSON 구조화, PII 마스킹, 중복 제거
                                    │
                                    ▼
 3. [ 머신러닝 분석 엔진 (ML Analytics Engine) ] ─────────────────┐
    • 동적 베이스라인 이상 탐지 (LSTM, Isolation Forest)          │
    • 사건 상관 분석 및 인시던트 군집화 (DBSCAN, Graph NN)        │
    • 토폴로지 기반 근본 원인 분석 (RCA: Root Cause Analysis)     │
    └───────────────────────────────┬─────────────────────────────┘
                                    │ (원인 후보 및 권고 조치 산출)
                                    ▼
 4. [ 자동 조치 및 협업 계층 (Action & Automation) ]
    • Low-Risk: 자동 런북 실행 (파드 재기동, 캐시 플러시, Auto-Scaling)
    • High-Risk: Jira 티켓 자동 발행 및 Slack 온콜 엔지니어 승인 요청 (Human-in-the-Loop)
```

선의 의미: 텔레메트리 데이터를 수집·정규화하여 ML 엔진이 분석하고 신뢰도에 따라 자동 조치 또는 온콜 승인으로 분기하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 수집 계층 (Ingestion) | 멀티 클라우드 및 K8s 환경의 **메트릭, 로그, 트레이스, 토폴로지 변경 이력 실시간 수집** |
| 전처리 계층 (Processing) | 이종 원천 데이터의 시간축을 정렬하고 **정규화 및 불필요한 노이즈 데이터 사전 필터링** |
| 머신러닝 엔진 (ML Engine) | 시계열 이상 탐지, **사건 상관 분석, 토폴로지 인과 그래프 기반 근본 원인(RCA) 도출** |
| 자동화 계층 (Automation) | 승인된 정책에 따라 **Ansible/K8s 런북을 자동 실행하여 무인 자율 복구(Self-Healing) 수행** |

#### 한줄 요약

- 수집 계층, 전처리 계층, ML 분석 엔진, 자동화 계층이 결합하여 지능형 자율 운영을 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **AIOps 장애 감지 및 복구 5단계**: 텔레메트리 정규화 $\to$ 이상 패턴 탐지 $\to$ 토폴로지 상관 분석 $\to$ 근본 원인(RCA) 도출 $\to$ 런북 자동 실행.

</details>

```text
[ AIOps 실시간 이상 탐지 및 자가 복구 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 이종 텔레메트리 신호 수집 및 정규화│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. ML 기반 동적 베이스라인 이상 패턴 감지│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 시간/토폴로지 기반 사건 상관 군집화 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 배포 변경점 대조 및 근본 원인(RCA) 도출
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 신뢰도 검증 후 자동 런북(Rollback) 실행
 └────────────────────────────────────────┘
```

### 동작 원리

1. 신호 정규화: Prometheus 메트릭, K8s 이벤트, Fluentbit 로그의 타임스탬프와 서비스 태그를 통일.
2. 이상 감지: AI 모델이 과거 3개월 트렌드와 비교하여 현재 트래픽 대비 비정상 응답 지연을 선제 감지.
3. 상관 군집화: 결제, 주문, DB 등 20개 파드에서 발생한 수백 개의 알람을 '결제 DB 커넥션 풀 고갈 1건'으로 묶음.
4. 원인 도출: 최근 5분 전 수행된 배포 변경점(Deployment)과 DB 쿼리를 인과 그래프로 분석하여 원인 확정.
5. 런북 실행: 위험도가 낮은 파드 재시작이나 롤백 런북을 자동 실행하고, 고위험 작업은 온콜에게 승인 요청.

#### 한줄 요약

- 정규화 $\to$ 이상 감지 $\to$ 상관 군집화 $\to$ RCA 도출 $\to$ 런북 실행의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전통적 규칙 기반 관제 vs AIOps**: 고정 임계치 사후 대응(Rule-Based)과 머신러닝 기반 사전 예측 및 인과 상관 분석(AIOps).

</details>

| 구분 | 전통적 규칙 기반 관제 (Rule-Based) | AIOps 지능형 IT 운영 (ML-Based) |
|:---|:---|:---|
| **적용 기준** | 단순 3-Tier 아키텍처, 정적 온프레미스 인프라 | 대규모 MSA, 하이브리드 멀티 클라우드, K8s 클러스터 |
| **핵심 특징** | **정적 임계치(CPU 80%) 초과 시 단순 경보, 사후 대응** | **동적 베이스라인 이상 탐지, 알람 90% 압축, 사전 예측** |
| **한계** | 수천 건 알람 폭증(경보 피로) 및 근본 원인 추론 불가 | AI 학습을 위한 고품질 데이터 확보 필요 및 초기 튜닝 기간 |

#### 한줄 요약

- 정적 룰 감시는 전통적 관제, 복잡한 대규모 분산 환경의 자율 복구는 AIOps를 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인간 개입 승인 모델(Human-in-the-Loop)**: AI가 내린 판단이 위험할 수 있으므로, 초기 도입 단계에서는 자동 조치 대신 권고안을 제시하고 사람이 승인 버튼을 누르는 운영 모델.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 원천의 규격 불일치로 인한 AI 모델 예측 왜곡 (GIGO) | **OpenTelemetry 기반 전사 텔레메트리 파이프라인 표준화 구축** | 학습 데이터 품질 및 예측 정확도 95% 달성 |
| AI 의사결정 과정을 알 수 없는 블랙박스(Black Box) 불신 | **설명 가능한 AI(XAI) 및 토폴로지 인과관계 트리 시각화 제공** | 원인 분석 신뢰도 및 엔지니어 채택률 확보 |
| AI의 오판으로 운영 중인 핵심 DB가 강제 재기동되는 사고 | **도입 초기 'Human-in-the-Loop' 승인제 적용 후 점진적 자동화** | 무단 오작동 사고 0건 달성 |

#### 한줄 요약

- 데이터 표준화, XAI 시각화, Human-in-the-Loop 승인제를 통해 AIOps의 안전성을 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **노옵스(NoOps)로의 진화**: AIOps가 성숙함에 따라 개발자가 코드를 푸시하면 배포, 관제, 튜닝, 복구까지 완전 무인화되는 자율 운영 체계.

</details>

- **AIOps** 기반 복잡성이 극대화된 클라우드 네이티브 환경을 관리하는 필수 지능형 운영 패러다임이며, OpenTelemetry 표준 데이터 파이프라인과 점진적인 Human-in-the-Loop 자동화를 결합하여 자율 운영(NoOps) 인프라를 완성해야 함

#### 한줄 요약

- 머신러닝 이상 탐지와 사건 상관 분석을 통해 알람 피로를 해소하고 자율 복구 IT 운영을 완성
