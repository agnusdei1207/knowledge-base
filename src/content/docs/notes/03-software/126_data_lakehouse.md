## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 레이크하우스(Data Lakehouse)**: 객체 스토리지에 원자성•일관성•격리성•지속성(Atomicity, Consistency, Isolation, Durability, ACID) 테이블 메타데이터를 결합해 여러 엔진이 공유하는 분석 구조이다.
- **ACID 테이블 메타데이터**: 테이블 버전 변경에 원자성•일관성•격리성•지속성을 제공하는 관리 정보이다.

</details>

- 정의/개념: 객체 저장소에 **ACID 테이블 메타데이터**를 결합한 **데이터 레이크하우스**이다.
- 배경/필요성: 레이크의 파일 단위 관리는 동시 쓰기•일관된 테이블 공유를 제약한다.

#### 한줄 요약

- 객체 스토리지에 ACID 테이블 메타데이터를 결합하여 여러 분석 엔진이 동일 테이블을 안전하게 공유한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **ACID 스냅숏**: 완성된 파일 집합만 하나의 원자 버전으로 공개하는 특성이다.
- **개방형 저장**: 여러 연산 엔진이 공개 명세에 따라 같은 객체 파일과 메타데이터를 공유하는 특성이다.
- **분리형 아키텍처**: 객체 저장 용량과 연산 엔진 자원을 독립적으로 확장하는 구조이다.

</details>

- 파일 변경을 원자 버전으로 공개하는 **ACID 스냅숏**이 핵심이다.
- 여러 연산 엔진이 객체 파일을 공유하는 **개방형 저장**이 핵심이다.
- 저장•연산 자원을 독립 확장하는 **분리형 아키텍처**가 핵심이다.

#### 한줄 요약

- 파일은 불변으로 저장하되 스냅숏 메타데이터가 현재 버전을 결정하므로 읽기 도중 테이블이 불완전하게 변경되지 않는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메타데이터 포인터**: 카탈로그가 현재 유효한 테이블 메타데이터 버전을 가리키는 참조이다.
- **객체 스토리지**: 불변 데이터 파일과 테이블 메타데이터 파일을 저장하는 계층이다.
- **테이블 메타데이터**: 오픈 테이블 포맷에 따라 스냅숏•스키마•파티션•통계를 관리하는 정보이다.
- **카탈로그**: 현재 유효한 테이블 메타데이터 포인터를 제공하는 구성요소이다.
- **연산 엔진**: 공유 테이블의 읽기•쓰기•변환•분석을 수행하는 실행 계층이다.
- **거버넌스**: 테이블과 데이터 파일의 접근 권한을 관리하는 활동이다.
- **유지관리**: 파일 병합과 오래된 스냅숏 만료를 수행하는 활동이다.

</details>

```text
[데이터 레이크하우스]
          |
          +-- [객체 스토리지]
          |          |
          |          +-- [테이블 메타데이터]
          |
          +-- [카탈로그]
          |
          +-- [연산 엔진]
          |
          +-- [거버넌스•유지관리]
```

선의 의미: 객체 스토리지와 테이블 메타데이터의 선은 불변 데이터•메타데이터 파일과 유효 스냅숏의 연결 관계, 테이블 메타데이터에서 갈라지는 선은 현재 포인터를 제공하는 카탈로그, 공유 테이블을 처리하는 연산 엔진, 권한•파일 병합•스냅숏 만료를 담당하는 거버넌스•유지관리의 결합 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 객체 스토리지 | **객체 스토리지**가 데이터•메타데이터 파일 저장 |
| 테이블 메타데이터 | **테이블 메타데이터**가 스냅숏•스키마 관리 |
| 카탈로그 | **카탈로그**가 현재 **메타데이터 포인터** 제공 |
| 연산 엔진 | **연산 엔진**이 공유 테이블의 읽기•쓰기•분석 수행 |
| 거버넌스•유지관리 | **거버넌스**와 **유지관리**가 권한•파일 병합•스냅숏 만료 관리 |

#### 한줄 요약

- 객체 스토리지, 테이블 메타데이터, 메타데이터 포인터, 연산 엔진, 거버넌스•유지관리로 구성된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **새 불변 데이터 파일 기록**: 기존 파일을 덮지 않고 변경 결과를 새 객체로 저장하는 단계이다.
- **새 스냅숏 메타데이터 구성**: 유효 파일 집합과 스키마•통계를 새 버전으로 만드는 단계이다.
- **기준 버전 비교•포인터 전환**: 충돌을 검사해 현재 테이블 참조를 원자적으로 바꾸는 단계이다.

</details>

```text
테이블 변경 요청
       |
       v
1. 새 불변 데이터 파일 기록
       |
       v
2. 새 스냅숏 메타데이터 구성
       |
       v
3. 기준 버전 비교•포인터 전환
       |
       +-- 충돌 --> 최신 버전에서 재시도
       |
       +-- 성공 --> 확정 스냅숏 공개
```

### 동작 원리

- **1. 새 불변 데이터 파일 기록**: **새 불변 데이터 파일 기록**은 기존 파일을 유지하고 변경 결과를 새 객체로 저장한다.
- **2. 새 스냅숏 메타데이터 구성**: **새 스냅숏 메타데이터 구성**은 유효 파일 집합•스키마•통계를 결합한다.
- **3. 기준 버전 비교•포인터 전환**: **기준 버전 비교•포인터 전환**은 충돌 검사 후 현재 참조를 원자적으로 전환한다.

#### 한줄 요약

- 새 데이터 파일과 스냅숏 메타데이터를 먼저 생성하고 마지막에 메타데이터 포인터만 원자적으로 전환하여 확정된 새 버전을 공개한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 레이크(Data Lake)**: 다양한 원천을 객체 파일로 원형에 가깝게 보존하고 읽기 시점에 해석하는 저장소이다.
- **데이터 웨어하우스(Data Warehouse)**: 공통 지표와 정형 이력을 관리형 표로 제공하는 분석 저장소이다.

</details>

| 분석 저장소 | 데이터 레이크하우스 | 데이터 레이크 | 데이터 웨어하우스 |
|:---|:---|:---|:---|
| 적용 기준 | **데이터 레이크하우스**: 트랜잭션과 다중 엔진 공유 | **데이터 레이크**: 다양한 원천 보존•재처리 | **데이터 웨어하우스**: 공통 지표 기반 고속 집계 |
| 핵심 특징 | 객체 파일과 **ACID 테이블 메타데이터** | 원형 객체와 스키마 온 리드 | 관리형 표와 스키마 온 라이트 |
| 한계 | 파일•스냅숏•엔진 호환 관리 | 품질•동시 쓰기•데이터 늪 | 데이터 복제•플랫폼 종속 비용 |


#### 한줄 요약

- 레이크하우스는 객체 스토리지 위에 다중 엔진이 공유하는 ACID 테이블 메타데이터를 결합한 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **목록 조회**: 테이블이 참조하는 파일과 메타데이터를 열거하는 작업이다.
- **읽기 계획**: 질의에 필요한 파일과 실행 태스크를 정하는 단계이다.
- **충돌 범위**: 동시 쓰기에서 겹침을 판정할 파일•파티션 단위이다.
- **재시도 정책**: 충돌한 커밋을 안전하게 다시 시도하는 규칙이다.
- **목표 파일 크기**: 읽기와 메타데이터 비용을 균형화할 파일 용량이다.
- **주기적 파일 병합**: 작은 파일을 목표 크기로 합치는 통제이다.
- **스냅숏 만료**: 보존 기간이 끝난 테이블 버전을 제거하는 활동이다.
- **파일 정리**: 어떤 스냅숏도 참조하지 않는 객체를 제거하는 활동이다.
- **버전 호환 시험**: 여러 엔진이 같은 테이블 형식 버전과 기능을 일관되게 읽고 쓰는지 확인하는 시험이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 같은 파일 집합을 동시에 바꾸면 커밋 충돌 발생 | **충돌 범위**와 **재시도 정책** 설계 | 동시 쓰기의 원자적 커밋 유지 |
| 작은 파일이 누적되면 **목록 조회**•**읽기 계획** 비용 증가 | **목표 파일 크기**와 **주기적 파일 병합** 적용 | 메타데이터•읽기 비용 감소 |
| 오래된 스냅숏과 미참조 파일 누적으로 저장 비용 증가 | 보존 기간 기반 **스냅숏 만료**•**파일 정리** | 메타데이터와 저장 공간 회수 |
| 엔진별 지원 기능 차이로 테이블 해석 불일치 | 공통 기능 범위와 **버전 호환 시험** 적용 | 다중 엔진의 읽기•쓰기 일관성 확보 |

#### 한줄 요약

- 새 데이터 파일을 모두 기록한 뒤 스냅숏으로 한 번에 공개하고 오래된 파일은 보존 기간 후 정리한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **오픈 테이블 포맷**: 다중 엔진이 객체 데이터를 같은 테이블 규칙으로 읽고 갱신하게 하는 공개 명세이다.

</details>

- 다중 엔진이 객체 데이터를 함께 갱신하면 **오픈 테이블 포맷** 기반 레이크하우스 구축이 핵심이다.

#### 한줄 요약

- 하나의 객체 스토리지를 다중 엔진이 공유하려면 메타데이터 포인터와 충돌 규칙, 스냅숏 만료•파일 정리를 함께 관리해야 한다.
