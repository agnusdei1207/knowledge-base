## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디지털 접근성 (WCAG 2.1)**: 장애인과 고령자를 포함한 모든 사용자가 제약 없이 디지털 정보와 기능을 동등하게 이용할 수 있도록 보장하는 W3C 웹 콘텐츠 접근성 지침.
- **POUR 4대 원칙**: Perceivable(인식 용이성), Operable(운용 용이성), Understandable(이해 용이성), Robust(견고성).

</details>

- 정의/개념: 장애인과 고령자를 포함한 모든 사용자가 **웹과 모바일의 정보와 기능을 동등하게 이용하도록 보장하는 W3C 접근성 표준(WCAG 2.1)**
- 배경/필요성: 복잡한 동적 SPA 및 이미지 중심 UI 확산으로 인한 **스크린 리더 등 보조기술(AT) 인식 불가 및 정보 취약 계층의 서비스 이용 차단 해결 불가**

#### 한줄 요약
- POUR 4대 원칙과 Level AA 기준을 준수하여 장애인의 동등한 디지털 과업 완수를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Semantic HTML & WAI-ARIA**: UI 요소의 역할(Role), 상태(State), 이름(Name)을 보조기술에 전달하는 표준 마크업 기술.
- **Color Contrast (명도 대비)**: 저시력자를 위해 텍스트와 배경 간의 명도 대비를 최소 4.5:1 이상(일반 텍스트 기준)으로 유지하는 지침.

</details>

- 대체 텍스트(Alt) 및 4.5:1 이상 명도 대비를 보장하는 **인식 용이성(Perceivable)**
- 마우스 없이 키보드만으로 모든 기능을 제어하는 **운용 용이성(Operable)**
- 논리적이고 예측 가능한 UI와 오류 정정 안내를 제공하는 **이해 용이성(Understandable)**
- 시맨틱 HTML 및 WAI-ARIA 기반 다양한 보조기술을 지원하는 **견고성(Robust)**

#### 한줄 요약
- 인식, 운용, 이해, 견고 4대 원칙을 바탕으로 보조기술과의 완벽한 상호운용성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **디지털 접근성 3대 연계 계층**: Semantic Markup Layer(웹 표준), Accessibility Tree Layer(브라우저 API), Assistive Tech Layer(스크린 리더).

</details>

```text
[디지털 접근성(WCAG 2.1) 및 보조기술 연계 아키텍처]
|-- 1. Web Content & Markup Layer (HTML5 시맨틱 태그, WAI-ARIA 속성, CSS 명도 대비)
|   |-- Semantic Elements: `<main>`, `<nav>`, `<button>`, `<label for="id">`
|   `-- WAI-ARIA State & Live Region: `aria-expanded`, `aria-live="polite"`
`-- 2. Browser Accessibility Tree Layer (브라우저가 DOM을 접근성 트리로 변환)
    |-- Name, Role, Value (요소의 이름, 역할, 상태를 OS 접근성 API로 노출)
    `-- OS Accessibility API (MSAA, UIA, NSAccessibility)
`-- 3. Assistive Technology Layer (보조기술 기기: 스크린 리더 NVDA/VoiceOver, 점자 디스플레이)
```

선의 의미: 계층 및 시맨틱 HTML이 브라우저의 접근성 트리를 생성하고 OS API를 통해 스크린 리더 등 보조기술에 전달되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **시맨틱 마크업 (HTML5)** | UI 요소의 본래 의미에 맞는 태그를 사용하여 **접근성 트리에 Name, Role, Value 제공** | 웹 표준 준수 |
| **WAI-ARIA 표준** | 커스텀 UI 및 동적 컴포넌트의 **열림/닫힘 상태(`aria-expanded`)와 동적 알림 전달**| 동적 상태 통지 |
| **키보드 내비게이션** | 마우스 없이도 **논리적 초점(Focus) 이동 순서와 모달 포커스 트랩(Focus Trap) 보장**| 키보드 100% 조작 |
| **스크린 리더 (Screen Reader)**| 시각장애인을 위해 **접근성 트리의 텍스트와 UI 컨트롤을 음성 및 점자로 실시간 출력**| 보조기술 인터페이스 |

#### 한줄 요약
- 시맨틱 HTML, WAI-ARIA, 키보드 내비게이션, 스크린 리더가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **접근성 품질 검증 5단계**: 핵심 과업 매핑 $\to$ 시맨틱/키보드 구현 $\to$ Axe 자동화 스캔 $\to$ 스크린 리더 수동 과업 검증 $\to$ 인증 마크 획득.

</details>

```text
디지털 서비스 접근성 개발 및 검증 착수
        │
   1. [핵심 과업 매핑] 회원가입, 결제, 민원 신청 등 핵심 과업을 WCAG 2.1 Level AA 기준과 매핑
        │
   2. [마크업 및 포커스 구현] 이미지 대체 텍스트(alt), 명시적 라벨, 모달 Focus Trap 구현
        │
   3. [자동화 스캔] CI 파이프라인에서 Axe-core를 실행하여 명도 대비 및 alt 누락 자동 검출
        │
   4. [스크린 리더 수동 검증] 전문 테스터가 화면을 끄고 NVDA와 키보드만으로 실제 결제 과업 완수
   ┌────┴───────────────────────────┐
  과업 완료 (Level AA 충족)         과업 차단 (결함 발견)
   │                                 │
5A. [품질인증 마크 획득]            5B. [마크업 및 포커스 디버깅]
   웹 접근성 공인 인증 획득              포커스 유실 결함 수정 후 재검증
   │                                 │
   └────┬────────────────────────────┘
        ▼
   디지털 포용성 및 법적 컴플라이언스 준수 완료
```

#### 한줄 요약
- 과업 매핑 → 마크업 구현 → 자동화 스캔 → 수동 과업 검증 → 인증 획득 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **WCAG 3대 적합성 수준**: Level A(최소 장벽 제거), Level AA(일반 상용/공공 권고 표준), Level AAA(특수 최고 수준).

</details>

| 비교 항목 | Level A (최소 적합 기준) | Level AA (일반 공공/기업 표준) | Level AAA (최고 수준 기준) |
|:---|:---|:---|:---|
| 핵심 준수 항목 | **대체 텍스트, 키보드 접근성, 캡차 대안** | **명도 대비 4.5:1 이상, 화면 200% 확대, 초점** | **명도 대비 7:1 이상, 수어 통역 비디오** |
| 법적 의무 수준 | 디지털 접근성의 가장 기초적인 진입 장벽 | **국내외 공공기관 및 대기업 법적 의무 기준** | 특수 장애인 전문 기관 권고 수준 |
| 디자인 제약도 | 낮음 (기본 태그 구조 준수로 충족) | **중간 (색상 명도 대비 및 폰트 크기 준수)** | 매우 높음 (디자인 자유도 극도로 제한) |
| 최적 적용 대상 | 단순 정보 제공형 정적 웹페이지 | **공공 포털, 금융권 뱅킹, 대형 e커머스 전반** | 특수 장애인 전용 복지 서비스 |

#### 한줄 요약
- 실무와 법적 표준은 Level AA를 목표로 설정하여 균형 잡힌 접근성을 보장한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Focus Trap**: 모달 팝업 오픈 시 Tab 키가 백그라운드 본문으로 빠져나가지 못하도록 모달 내부에 가두고, 닫힐 때 원래 열었던 버튼으로 초점을 복귀시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SPA 환경에서 모달 창 오픈 시 스크린 리더 포커스 유실 | **모달 내 `Focus Trap` 구현 및 닫힘 시 트리거 버튼으로 초점 복귀** | 키보드 탐색 완결성 100% 보장 |
| 이미지에 "image.png", "배너" 등 무의미한 대체 텍스트 입력 | **이미지의 비즈니스 목적과 전달 정보를 기술한 의미 있는 Alt 작성** | 시각장애인 정보 습득 정확도 확보 |
| Axe 등 자동화 도구 100점 통과만 믿고 실제 과업 수행 불가 | **실제 시각/지체 장애인 테스터의 '핵심 사용자 과업 완수 평가' 병행** | 실질적 디지털 접근성 달성 |
| 동적 비동기 알림(토스트 메시지) 발생 시 스크린 리더 미낭독 | **`aria-live="polite"` 속성을 적용하여 실시간 동적 상태 안내** | 실시간 정보 소외 방지 |

#### 한줄 요약
- Focus Trap, 의미 있는 대체 텍스트, 실수요자 과업 검증, aria-live로 운영한다.

## Ⅶ. 결론

- 디지털 정보화 사회에서 모든 시민의 보편적 기본권을 보장하고 ESG 경영을 실천하기 위해 **W3C WCAG 2.1 Level AA 표준을 개발 수명주기 전반에 내재화**하고, **Axe 기반의 CI 자동화 스캔과 실수요자 기반의 스크린 리더 과업 검증**을 결합하여 완전한 디지털 포용성 완성

#### 한줄 요약
- 디지털 접근성은 POUR 4대 원칙과 Level AA 기준을 준수하여 정보 취약 계층의 평등한 디지털 이용권을 보장하는 핵심 소프트웨어 엔지니어링 품질이다.
