## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **저지연 추론(Low-Latency Inference)**: 클라우드 서버로 데이터를 송수신하는 과정 없이, 단말기 내부 프로세서를 활용해 즉각적으로 결과를 반환하여 네트워크 왕복 시간(RTT)을 원천적으로 제거한 추론 방식이다.
- **오프라인 추론(Offline Inference)**: 인터넷이나 통신 네트워크 연결이 완전히 끊어진 상태 혹은 제한된 환경에서도, 단말기에 내장된 모델을 통해 정상적으로 AI 기능을 수행하는 독립적 추론 환경이다.
- **인공지능(Artificial Intelligence, AI)**: 방대한 데이터 기반으로 학습된 수학적 모델과 알고리즘을 활용하여 인간의 인지 능력이 필요한 인식, 예측, 생성 작업을 자동 수행하는 고도화된 소프트웨어 기술이다.
- **온디바이스 모델 배포(On-Device Model Deployment)**: 서버 최적화된 거대 AI 모델을 단말 환경에 맞게 압축·경량화하고 전용 추론 런타임과 함께 기기에 직접 설치하여, 모든 데이터 처리와 판단을 기기 내부에서 완결짓는 차세대 모델 배포 아키텍처이다.

</details>

- 정의/개념: 고성능 **인공지능(AI)** 모델을 모바일 및 엣지 단말에 최적화하여 설치함으로써, 강력한 개인정보 보호와 즉각적인 **저지연 추론(Low-Latency Inference)** 및 **오프라인 추론(Offline Inference)**을 제공하는 **온디바이스 모델 배포(On-Device Model Deployment)** 기술이다.
- 배경/필요성: 기존의 중앙집중형 클라우드 추론 방식은 예측 불가능한 네트워크 지연, 막대한 트래픽 전송 비용, 프라이버시 데이터의 외부 유출 위험 등을 수반하므로 이를 근본적으로 해결하기 위해 단말 자체 연산력이 필수적으로 요구된다.

#### 한줄 요약
- 스마트폰이나 IoT 기기의 제한된 메모리와 배터리 환경에 맞게 AI 모델을 압축 탑재하여, 네트워크 연결 없이도 안전하고 즉각적인 지능형 판단을 수행하는 에지 배포 기술

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **LiteRT (구 TensorFlow Lite)**: 경량화된 머신러닝 모델을 모바일 기기나 임베디드 단말의 CPU, GPU, NPU 등 다양한 이기종 하드웨어 가속기에서 고속으로 실행할 수 있도록 최적화된 구글 기반의 추론 런타임 엔진이다.
- **개방형 신경망 교환(Open Neural Network Exchange, ONNX)**: PyTorch, TensorFlow 등 서로 다른 딥러닝 프레임워크 환경에서 학습된 모델의 그래프 구조와 가중치를 상호 호환 가능하도록 규격화한 산업 표준 포맷이다.
- **무선 소프트웨어 갱신(Over-The-Air, OTA)**: 기기를 서비스 센터에 입고하거나 유선 연결할 필요 없이, 통신 네트워크를 통해 단말기에 설치된 AI 모델 가중치나 런타임 소프트웨어 패키지를 원격으로 실시간 배포 및 업데이트하는 체계이다.
- **폴백(Fallback)**: 기기 내부의 추론이 가용 자원 부족이나 처리 오류로 실패하거나, 결과의 신뢰도 점수가 사전 정의된 품질 기준을 밑돌 때 이전 안정 버전이나 강력한 클라우드 서버 경로로 요청을 자동 전환하는 우회 장애 조치 방식이다.
- **양자화(Quantization)**: 모델의 가중치 변수와 연산 과정에 사용되는 32비트 부동소수점(FP32) 데이터를 8비트 정수(INT8) 등 더 낮은 수치 정밀도로 변환하여, 모델의 저장 크기와 메모리 대역폭 요구량을 줄이고 추론 속도를 획기적으로 높이는 핵심 경량화 기법이다.
- **가지치기(Pruning)**: 신경망 내에서 결과에 미치는 영향력이 미미한 뉴런 간의 연결 가중치를 0으로 제거함으로써, 모델의 파라미터 개수를 대폭 줄이고 연산량을 최소화하여 추론 효율성을 극대화하는 기법이다.

</details>

- **양자화(Quantization)**와 **가지치기(Pruning)** 등 모델 압축 알고리즘을 선행 적용하여 단말의 한정된 저장 공간을 절약하고 전력 소모를 억제한다.
- **LiteRT** 포맷 변환 및 **개방형 신경망 교환(ONNX)** 규격화를 거친 경량 모델이 대상 기기의 실제 NPU/GPU 가속 환경에서 원활히 동작하는지 사전 검증한다.
- 통신망 기반의 **무선 소프트웨어 갱신(OTA)** 시스템을 활용해 점진적으로 배포하며, 현장 성능 모니터링을 통한 클라우드 **폴백(Fallback)** 라우팅으로 배포 리스크를 이중 통제한다.

#### 한줄 요약
- 하드웨어 제약을 극복하기 위한 수치 정밀도 축소와 모델 규격 표준화를 기반으로, 이기종 칩셋 환경에서의 호환성 검증과 장애 시의 서버 우회 경로를 확보하는 안전한 분산 추론 체계

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **기기 추론 런타임(Device Inference Runtime)**: 다운로드된 모델의 계산 그래프를 파싱(Parsing)하고, 단말기에 내장된 CPU, GPU, NPU 중 가장 적합하고 지원 가능한 하드웨어 연산기에 작업을 할당 및 스케줄링하는 코어 실행 엔진이다.
- **중앙 처리장치(CPU)**: 시스템의 전반적인 제어 흐름과 복잡한 조건부 범용 연산을 담당하며, 상대적으로 병렬 연산력은 낮으나 모든 기기에 기본 탑재된 범용 프로세서이다.
- **그래픽 처리장치(GPU)**: 수천 개의 코어를 활용하여 단정밀도 부동소수점 행렬 연산을 고속으로 병렬 처리함으로써, 컴퓨터 비전 등 특정 딥러닝 연산의 추론 속도를 대폭 끌어올리는 가속 프로세서이다.
- **신경망 처리장치(NPU)**: 인공지능의 핵심인 행렬 곱셈 및 덧셈(MAC) 연산을 극소화된 전력 소모로 전담 가속하기 위해 설계된 AI 전용 특수 목적 하드웨어 실리콘 칩이다.
- **경량 모델 패키지(Lightweight Model Package)**: 단말기에서 즉시 구동될 수 있도록 압축된 가중치 파일, 런타임 호환 연산자 목록, 보안 서명(Signature), 그리고 버전 메타데이터를 하나의 컨테이너로 묶은 독립적 배포 단위이다.
- **온디바이스 애플리케이션(On-Device Application)**: 카메라나 마이크 센서로부터 들어오는 원시 데이터를 기기 내에서 전처리하고, 런타임 추론을 호출한 뒤 결과값을 응용하여 최종적인 사용자 경험(UX)이나 비즈니스 로직을 구현하는 최상위 소프트웨어 레이어이다.
- **배포•관측 제어기(Deployment & Observation Controller)**: OTA 기반의 패키지 다운로드 관리, 백그라운드 추론 성능(지연 시간, 배터리 소모) 관측, 그리고 이상 징후 감지 시 구버전 롤백이나 클라우드 폴백을 결정하는 운영 통제 모듈이다.

</details>

```text
온디바이스 모델 구조
      |
      +-- 모델•실행
      |         +-- [경량 모델 패키지]
      |         +-- [기기 추론 런타임]
      |         +-- [CPU•GPU•NPU]
      |
      +-- 운영
                +-- [온디바이스 애플리케이션]
                +-- [배포•관측 제어기]
```

| 구성요소 | 책임 |
|:---|:---|
| **경량 모델 패키지(Lightweight Model Package)** | 압축 완료된 가중치 텐서, 연산자 명세, 서명 및 버전 정보의 무결성 보관 |
| **기기 추론 런타임(Device Inference Runtime)** | 모델 그래프 파싱 및 최적화, 지원 가능한 기기 가속기와의 인터페이스 처리 |
| **CPU•GPU•NPU(프로세서 코어)** | 각 기기의 칩셋 특성에 맞게 할당된 계층별 AI 텐서 연산을 고속 처리 |
| **온디바이스 애플리케이션(On-Device App)** | 센서 입력 데이터 정제, 추론 요청 스케줄링, 예측 결과 기반의 비즈니스 로직 실행 |
| **배포•관측 제어기(Deployment & Observation Controller)** | 단계적 OTA 배포 스케줄 관리, 실시간 현장 품질 지표 수집 및 긴급 폴백 메커니즘 가동 |

#### 한줄 요약
- 최적화된 런타임과 AI 전용 칩셋이 패키징된 경량 모델을 효율적으로 처리하고, 애플리케이션 레이어와 배포 제어기가 이를 안전하게 감싸 단말기 독립적 서비스를 제공하는 엔드투엔드 아키텍처

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 경량 모델 후보 전달(Lightweight Model Candidate Delivery)**: 클라우드 환경에서 양자화, 가지치기 및 LiteRT/ONNX 형식 변환을 완료한 여러 파라미터 조합의 잠재적 배포 후보 패키지들을 디바이스 팜(Device Farm) 테스트 환경으로 이관하는 단계이다.
- **2. 호환성•품질•자원 검증(Compatibility•Quality•Resource Verification)**: 타겟이 되는 파편화된 기기군(제조사, OS, 칩셋별)을 대상으로 실제 추론 정확도(F1-Score), 레이턴시, 피크 메모리 점유율, 발열 및 배터리 소모량을 종합 벤치마크하는 단계이다.
- **3. 승인 버전 등록(Approved Version Registration)**: 엄격한 검증 기준을 통과한 기기군 맞춤형 최적 버전을 릴리즈 저장소에 정식 등록하고, 장애 발생 시 즉각 롤백할 수 있는 대체(Fallback) 버전 매핑 정보를 확정하는 단계이다.
- **4. 단계별 OTA 배포(Phased OTA Deployment)**: 무결성 서명이 완료된 최종 승인 모델을 전체 사용자에게 일괄 배포하지 않고, 소규모 비율(예: 1% -> 10%)의 기기에만 우선 배포(Canary)하여 현장 영향을 점진적으로 모니터링하는 단계이다.
- **5. 지연•오류•전력 전달(Latency•Error•Power Feedback Delivery)**: 프로덕션 기기들이 실제 동작하며 겪는 추론 지연, 런타임 크래시 로그, 비정상적 배터리 드레인 현상 등의 원격 측정(Telemetry) 데이터를 중앙 배포 제어기로 실시간 피드백하는 단계이다.

</details>

```text
1. 경량 모델 후보 전달
      |
      v
2. 호환성•품질•자원 검증
      |
      +-- 특정 기기군에서 자원 한계 또는 품질 미달 --> 해당 타겟용 경량화 및 변환 재설계 지시
      |
      +-- 품질/성능 기준 통과
              |
              v
3. 승인 버전 등록
      |
      v
4. 단계별 OTA 배포
      |
      v
5. 지연•오류•전력 전달
      |
      +-- 현장 단말 임계 지표 이탈 감지 --> 이전 안정 모델 롤백 또는 서버 폴백 즉각 발동
      |
      +-- 모든 지표 정상 범위 충족 --> 배포 대상 기기군 비율 단계적 확대(Roll-out)
```

### 동작 원리

1. **경량 모델 후보 전달(Lightweight Model Candidate Delivery)**: 양자화율과 가지치기 강도가 다른 다수의 런타임 변환 후보군을 셋업한다.
2. **호환성•품질•자원 검증(Compatibility•Quality•Resource Verification)**: 물리적 단말 테스트베드에서 레이턴시 병목, NPU 지원 여부, 정확도 손실폭을 정밀 측정한다.
3. **승인 버전 등록(Approved Version Registration)**: 기기군 파편화(Fragmentation)에 대응하는 맞춤형 버전 카탈로그와 긴급 복구 플랜을 승인 처리한다.
4. **단계별 OTA 배포(Phased OTA Deployment)**: 리스크를 분산하기 위해 소규모 사용자부터 링(Ring) 단위 무선 업데이트를 수행한다.
5. **지연•오류•전력 전달(Latency•Error•Power Feedback Delivery)**: 인더와일드(In-the-wild) 환경의 단말 상태 텔레메트리 기반으로 배포 중단 및 복귀 의사결정을 실시간 수행한다.

#### 한줄 요약
- 단말기 파편화를 고려한 철저한 이기종 물리 검증부터 카나리 방식의 점진적 무선 배포까지, 하드웨어 제약 리스크를 최소화하는 풀 사이클 릴리즈 파이프라인

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **온디바이스 추론(On-Device Inference)**: 사용자의 민감한 개인정보나 대용량 미디어 입력을 외부로 유출하지 않고 기기 내부의 NPU/GPU를 전적으로 활용해 고속으로 경량 모델을 실행하는 방식이다.
- **클라우드 추론(Cloud Inference)**: 단말기에서 수집한 입력 데이터를 초고속 네트워크를 통해 데이터센터로 전송한 후, 막대한 파라미터를 가진 고성능 대규모 모델(LLM 등)과 거대 GPU 클러스터를 활용하여 정밀도 높은 결과를 반환하는 방식이다.
- **하이브리드 추론(Hybrid Inference)**: 가벼운 일상적 요청은 기기 단말에서 즉각 처리하여 비용과 지연을 줄이고, 기기 성능 한계를 초과하는 복잡한 요청이나 고품질 생성이 필요할 때만 서버 측 모델로 라우팅하는 지능형 스위칭 방식이다.

</details>

| AI 추론 배치 방식 | **온디바이스 추론(On-Device Inference)** | **클라우드 추론(Cloud Inference)** | **하이브리드 추론(Hybrid Inference)** |
|:---|:---|:---|:---|
| 적용 기준 | 즉각적인 반응 속도, 절대적 보안 필요성, 네트워크 단절 등 오프라인 요구 환경 | 거대 매개변수 모델 필수, 고도의 정밀도 요구, 잦은 중앙 통합 지식 갱신 환경 | 단말 기종 간 성능 편차가 크거나 쿼리 복잡도에 따라 가변적인 컴퓨팅 요구 환경 |
| 핵심 특징 | 네트워크 왕복 없이 기기 자체 컴퓨팅 파워로 경량화 모델 독립 실행 | 무한에 가까운 서버 확장성을 바탕으로 최상위 성능의 무거운 모델 구동 | 단말 라우터가 난이도를 판별하여 기기 자체 처리와 서버 처리를 유연하게 분기 |
| 한계 | 단말 칩셋/OS 파편화 대응의 어려움, 배터리 소모 및 극심한 저장 용량 제약 | 망 지연으로 인한 실시간성 저하, 지속적 대규모 클라우드 인프라 유지 비용 발생 | 오프라인과 온라인 모델 간의 출력 결과 편차(일관성 저하) 및 아키텍처 구현 복잡도 상승 |

> 요약: 궁극적 지능형 인프라 구현을 위해 극단적인 대형 연산은 클라우드에, 초저지연·보안 연산은 단말에 배치하되, 롱테일 기기 파편화는 하이브리드 라우팅으로 해결하는 전략이다.

#### 한줄 요약
- 요구되는 모델의 복잡도, 사용자의 프라이버시 수준, 네트워크 가용성을 다각도로 평가하여 가장 경제적이고 안정적인 추론 실행 위치를 설계하는 아키텍처 결정 기준

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **정확도 저하(Accuracy Degradation)**: 모델의 크기를 무리하게 줄이기 위해 과도한 저정밀도 양자화(INT8 이하)나 극단적 가지치기를 적용할 경우, 원본 FP32 모델 대비 비즈니스 수용 한계치를 밑도는 수준으로 인식/예측 품질이 폭락하는 트레이드오프 문제이다.
- **카나리 배포(Canary Deployment)**: 광산의 카나리아처럼 잠재적 치명 결함을 사전에 탐지하기 위해, 전체 사용자 트래픽의 극소수(예: 1~5%) 기기에만 신규 AI 모델 패키지를 먼저 적용하여 실 환경 안정성을 관측하는 점진적 배포 전략이다.
- **자동 롤백(Automatic Rollback)**: 배포 이후 수집된 단말의 앱 크래시 비율, 런타임 지연, 배터리 발열 지표 등이 사전에 설정된 정상 임계치를 이탈하는 즉시, 인간의 개입 없이 시스템이 알아서 검증된 직전 안정 버전 모델로 되돌려 장애 확산을 차단하는 자율 복구 체계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기기 제조사별 NPU 가속기 및 가용 메모리 극심한 편차 | 단말 등급/티어(Tier)별 호환성 분리 시험 및 기종별 맞춤형 모델 패키지(Variant) 병렬 생성 | 특정 구형 단말에서의 런타임 크래시 및 배포 실패율 획기적 축소 |
| 과도한 양자화 압축으로 인한 심각한 **정확도 저하(Accuracy Degradation)** | 도메인 특화 대표 데이터셋(Calibration Set)을 활용한 양자화 인식 학습(QAT) 및 허용 오차 사전 시뮬레이션 | 획기적인 모델 경량화 비율을 달성하면서도 비즈니스 요구 품질선(Baseline) 엄격 보장 |
| 기기 내부에 탑재된 기업 핵심 모델의 리버스 엔지니어링 및 탈취 위험 | 가중치 암호화(Encryption), 런타임 메모리 난독화, 운영체제 단위의 보안 영역(TrustZone/Keystore) 활용 모델 키 보호 체계 적용 | 수백만 달러의 학습 비용이 투입된 기업 고유 지식재산권(IP)의 악의적 외부 유출 원천 차단 |
| OTA 과정에서의 파일 손상이나 예기치 않은 오류로 인한 단말 오배포 사태 | 암호학적 무결성 서명 체계 확립, 안전한 **카나리 배포(Canary Deployment)** 모니터링, 임계치 초과 시 즉각적인 **자동 롤백(Automatic Rollback)** 연동 | 치명적인 엣지 단말 장애 발생 시 서비스 중단 시간을 최소화하는 압도적 현장 복구 탄력성 확보 |

#### 한줄 요약
- 무리한 압축으로 인한 품질 폭락을 경계하면서도 기종별 특화 테스트로 파편화를 극복하고, 암호화 기반 보안과 자율 복구 배포 파이프라인으로 안전성을 극대화하는 현장 운영 가이드

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **추론 배치 방식 선택 기준(Inference Deployment Selection Criteria)**: 대상 단말의 프로세싱 연산력과 가용 배터리가 충분하고 프라이버시가 중요하다면 온디바이스를, 거대 파라미터 연산이 필수적이라면 클라우드를, 그리고 다양한 기기 편차 속에서 안정성과 비용 효율을 모두 잡아야 한다면 하이브리드 아키텍처를 전략적으로 채택하는 최상위 설계 판단 기준이다.

</details>

- **추론 배치 방식 선택 기준(Inference Deployment Selection Criteria)**에 입각하여 단말의 컴퓨팅 자원 충족 시 온디바이스 모델을 적극 도입하되, 압축으로 인한 정확도 손실이 비즈니스 허용치를 넘는 환경에서는 즉각 하이브리드 라우팅으로 전환하고 엣지 장애 발생 시 **자동 롤백(Automatic Rollback)** 메커니즘을 구비한 무중단 서비스 아키텍처 구현 필수

#### 한줄 요약
- 단순한 모델 용량 압축을 넘어 다변화된 엣지 디바이스 환경에서의 실질적 구동 안정성을 입증하고, 예측 불가능한 단말 장애에 대비한 하이브리드 우회와 자율 롤백 체계 적용 필수
