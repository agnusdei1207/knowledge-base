## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **저지연 추론**: 단말 내부 실행으로 네트워크 왕복 시간을 제거한 추론이다.
- **오프라인 추론**: 네트워크 연결 없이 단말 내부에서 수행하는 추론이다.
- **인공지능(Artificial Intelligence, AI)**: 학습된 모델로 인식•예측•생성을 수행하는 기술이다.
- **온디바이스 모델 배포(On-Device Model Deployment)**: 학습된 모델과 추론 런타임을 단말에 설치해 입력을 기기 내부에서 처리하는 배포 방식이다.

</details>

- 정의/개념: 모델을 단말에 설치해 **저지연•오프라인 추론**을 제공하는 방식
- 배경/필요성: 클라우드 추론은 **망 지연•전송 비용•정보 노출**

#### 한줄 요약

- 기기의 작은 작업 공간과 배터리에 맞게 모델을 줄여 인터넷이 없어도 바로 판단하게 한다

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **LiteRT**: 경량 모델을 모바일•내장형 단말의 중앙•그래픽•신경망 처리장치에서 실행하도록 최적화한 추론 런타임이다.
- **개방형 신경망 교환(Open Neural Network Exchange, ONNX)**: 학습•추론 도구 사이에서 모델 그래프와 가중치를 교환하는 표준 형식이다.
- **무선 소프트웨어 갱신(Over-The-Air, OTA)**: 네트워크를 통해 단말의 모델이나 소프트웨어 패키지를 원격 배포하는 방식이다.
- **폴백(Fallback)**: 기기 추론이 실패하거나 품질 기준을 충족하지 못할 때 이전 모델이나 서버 경로로 전환하는 방식이다.

</details>

- **양자화•가지치기**로 크기•지연•전력 감소
- **LiteRT•ONNX** 모델 변환과 **가속기 호환성** 검증
- **단계 OTA•관측•폴백**으로 현장 배포 위험 통제

#### 한줄 요약

- 같은 모델도 기기 칩과 실행 엔진이 다르면 속도와 배터리가 달라 실제 기기에서 확인해야 한다

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **기기 추론 런타임**: 기기 추론 런타임은 모델 그래프를 해석하고 CPU•GPU•NPU에서 지원되는 연산기로 실행한다.
- **중앙 처리장치(Central Processing Unit, CPU)**: 범용 연산과 제어를 수행하는 프로세서이다.
- **그래픽 처리장치(Graphics Processing Unit, GPU)**: 다수 연산을 병렬 수행해 모델 계산을 가속하는 프로세서이다.
- **신경망 처리장치(Neural Processing Unit, NPU)**: 행렬 연산 등 인공지능 추론을 저전력으로 가속하도록 설계된 전용 프로세서이다.
- **경량 모델 패키지(Lightweight Model Package)**: 단말용 모델 가중치•연산자•버전•서명을 함께 담은 배포 단위이다.

</details>

```text
온디바이스 모델 구조
      |
      +-- 모델•실행
      |         +-- [경량 모델 패키지]
      |         +-- [기기 추론 런타임]
      |         +-- [CPU•GPU•NPU]
      |
      +-- 운영
                +-- [온디바이스 애플리케이션]
                +-- [배포•관측 제어기]
```

| 구성요소 | 책임 |
|:---|:---|
| 경량 모델 패키지 | **가중치•연산자•버전** 보관 |
| 기기 추론 런타임 | 모델 그래프를 **지원 연산기로 실행** |
| CPU•GPU•NPU | 기기별 지원 연산을 **NPU 등 가속기**로 실행 |
| 온디바이스 애플리케이션 | **전처리•추론•결과 사용** |
| 배포•관측 제어기 | **OTA•품질 관측•폴백** 관리 |


#### 한줄 요약

- 줄인 모델을 기기 칩에서 실행하고 문제가 생기면 이전 모델이나 클라우드 경로로 바꾼다

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **4. 단계별 OTA 배포**: 승인한 기기군별 모델을 서명한 OTA 패키지로 소수 기기부터 배포하고 관측 결과에 따라 확대한다.
- **1. 경량 모델 후보 전달**: 양자화•가지치기•변환 형식을 고정한 후보 패키지를 시험기에 전달하는 단계이다.
- **2. 호환성•품질•자원 검증**: 실제 기기군별 정확도•지연•메모리•전력 사용량을 측정하는 단계이다.
- **3. 승인 버전 등록**: 기기군별 합격 버전과 장애 시 복귀할 버전을 지정하는 단계이다.
- **5. 지연•오류•전력 전달**: 현장 기기의 실행 품질과 자원 신호를 배포 제어기에 환류하는 단계이다.

</details>

```text
1. 경량 모델 후보 전달
      |
      v
2. 호환성•품질•자원 검증
      |
      +-- 기기군 기준 미달 --> 경량화•변환 재설계
      |
      +-- 기준 통과
              |
              v
3. 승인 버전 등록
      |
      v
4. 단계별 OTA 배포
      |
      v
5. 지연•오류•전력 전달
      |
      +-- 현장 기준 이탈 --> 이전 모델•서버 폴백
      |
      +-- 기준 충족 --> 대상 기기군 확대
```

**동작 원리**

1. **경량 모델 후보 전달**: **양자화•가지치기•형식** 고정
2. **호환성•품질•자원 검증**: 기기별 **정확도•지연•전력** 측정
3. **승인 버전 등록**: 기기군별 **합격•폴백 버전** 지정
4. **단계별 OTA 배포**: **소수 기기부터** 버전 확대
5. **지연•오류•전력 전달**: 기기군별 **실행•품질 신호** 수집


#### 한줄 요약

- 모델을 작게 만든 뒤 실제 기기별로 속도•정확도•배터리를 확인하고 일부부터 배포한다

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **온디바이스 추론**: 온디바이스 추론은 민감 입력을 단말 내부의 경량 모델로 처리해 지연과 네트워크 의존을 줄인다.
- **클라우드 추론(Cloud Inference)**: 입력을 서버로 전송해 중앙의 대형 모델과 고성능 자원으로 처리하는 방식이다.
- **하이브리드 추론(Hybrid Inference)**: 기기에서 우선 판단하고 자원•품질 조건에 따라 서버 추론으로 전환하는 방식이다.

</details>

| AI 추론 배치 방식 | 온디바이스 추론 | 클라우드 추론 | 하이브리드 추론 |
|:---|:---|:---|:---|
| 적용 기준 | 저지연•오프라인•**민감정보** | 대형 모델•**중앙 갱신** | 기기 자원•**품질 편차** |
| 핵심 특징 | 기기 내부 **경량 모델 실행** | 서버의 **고성능 모델 실행** | 기기 판정 후 **서버 폴백** |
| 한계 | 단편화•전력•**용량 제한** | 망 지연•**전송 비용** | 경로 일관성•**운영 복잡도** |

> 요약: 대형 모델은 클라우드, 저지연은 기기, 자원 편차는 하이브리드

#### 한줄 요약

- 큰 모델이 필요하면 서버, 즉시 판단하면 기기, 기기별 여유가 다르면 두 경로를 함께 쓴다

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **정확도 저하**: 정확도 저하는 양자화나 가지치기로 모델 표현력이 줄어 원본 모델보다 예측 품질이 낮아지는 문제다.
- **양자화(Quantization)**: 가중치와 연산의 수치 정밀도를 낮춰 모델 크기•지연•전력 사용을 줄이는 기법이다.
- **가지치기(Pruning)**: 영향이 작은 연결이나 가중치를 제거해 모델 계산량과 크기를 줄이는 기법이다.
- **카나리 배포(Canary Deployment)**: 새 모델을 소수 기기에 먼저 배포해 문제를 관찰한 뒤 범위를 확대하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기기별 **가속기•메모리 차이** | 기기 등급별 **호환 시험** | 배포 실패 **축소** |
| 양자화의 **정확도 저하** | 대표 자료•**허용 오차 검증** | 경량화 품질 **보장** |
| 단말 모델의 **추출 위험** | 암호화•난독화•**키 보호** | 지식재산 **노출 축소** |
| OTA 모델의 **오배포** | 서명•Canary•**자동 롤백** | 현장 장애 **복구성** |

#### 한줄 요약

- 음성 모델은 칩 종류마다 단어 정확도와 응답 속도를 확인해 맞는 버전을 배포한다



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **하이브리드**: 단말 자원과 품질을 충족하면 온디바이스를 사용하고 정확도 손실이 크거나 기기 편차가 크면 하이브리드로 배포한다.
- **자동 롤백(Automatic Rollback)**: 현장 지표가 기준을 벗어나면 배포 제어기가 이전 정상 모델 버전으로 자동 복귀시키는 절차이다.

</details>

- 자원 충족 단말은 **온디바이스**, 정확도 손실이 크면 **하이브리드** 배포

#### 한줄 요약

- 모델 크기만 줄이지 말고 실제 기기에서 품질과 배터리를 확인한 뒤 안전한 복귀 경로까지 준비한다
