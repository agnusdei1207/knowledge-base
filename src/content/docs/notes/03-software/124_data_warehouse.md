## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 웨어하우스 4대 특성(Inmon/Kimball)**: 주제 지향성(Subject-Oriented: 비즈니스 주제별 구성), 통합성(Integrated: 전사 일관된 명명/코드), 시계열성(Time-Variant: 이력 스냅샷 보존), 비휘발성(Non-Volatile: 읽기 전용 영구 보존).
- **OLTP 성능 급락 및 지표 불일치(OLTP Degradation & Inconsistent Metric)**: 실시간 트랜잭션 DB에서 대규모 분석 집계를 직접 수행하여 운영 장애를 유발하고 부서별 지표가 상이해지는 문제.

</details>

- 정의/개념: 기업의 의사결정을 지원하기 위해 **주제 지향성, 통합성, 시계열성, 비휘발성의 4대 특성을 바탕으로 이력 데이터를 정제·저장**하는 분석용 데이터 저장소
- 배경/필요성: 운영 OLTP DB를 대상으로 직접 대규모 통계 쿼리 실행 시 발생하는 **트랜잭션 성능 급락, 지표 정의 불일치 및 다차원 분석 한계** 직면

#### 한줄 요약

- 전사 원천 데이터를 통합·정제하여 비즈니스 의사결정과 OLAP 다차원 분석을 지원하는 중앙 데이터 저장소

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스타 스키마(Star Schema)**: 중앙의 사실 테이블(Fact Table)과 주변의 비정규화된 차원 테이블(Dimension Table)이 1단계로 직결되는 차원 모델링 구조.
- **느리게 변하는 차원(SCD: Slowly Changing Dimension)**: 고객 주소 등 시간 흐름에 따라 변화하는 차원 속성의 과거 이력을 보존하기 위한 기법(Type 2: 신규 행 추가).

</details>

- 주제 지향성, 통합성, 시계열성, 비휘발성의 **4대 고유 특성 완비**
- Fact Table(측정값)과 Dimension Table(분석 축) 기반의 **차원 모델링(Dimensional Modeling)**
- 대용량 집계 쿼리를 가속화하는 **열 지향 저장(Columnar Storage) 및 OLAP 지원**

#### 한줄 요약

- 4대 특성과 스타 스키마 기반 차원 모델링을 통해 복합 분석 쿼리를 고속으로 처리

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Fact Table vs Dimension Table**: 매출액, 수량 등 수치적 측정값(Measure)을 저장하는 Fact Table과 고객, 상품, 시간 등 분석 기준 속성을 저장하는 Dimension Table.

</details>

```text
[ 데이터 웨어하우스 스타 스키마(Star Schema) 아키텍처 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │                      Data Warehouse Star Schema                        │
 ├────────────────────────────────────────────────────────────────────────┤
 │   [ Dim_Customer (고객차원) ]                 [ Dim_Product (상품차원) ] │
 │   (Customer_ID, City, Segment)               (Product_ID, Category)    │
 │                │                                           │           │
 │                └─────────────────────┬─────────────────────┘           │
 │                                      ▼                                 │
 │                       ┌──────────────────────────────┐                 │
 │                       │ Fact_Sales (매출 사실 테이블)│                 │
 │                       │ - Sales_ID (PK)              │                 │
 │                       │ - Customer_ID, Product_ID(FK)│                 │
 │                       │ - Amount, Quantity (Measures)│                 │
 │                       └──────────────▲───────────────┘                 │
 │                                      │                                 │
 │                           [ Dim_Date (날짜차원) ]                       │
 │                           (Date_ID, Year, Quarter, Month)              │
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 중앙의 Fact Table(측정값)과 주변의 Dimension Table(분석 축)이 직접 1:N 연결되는 스타 스키마 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 사실 테이블 (Fact Table) | 매출액, 판매 수량 등 비즈니스 수치 측정값(Measure)과 **외래키(FK)를 정밀 보관** |
| 차원 테이블 (Dimension) | 분석의 기준이 되는 고객, 상품, 지역, 일자의 **상세 설명 속성 및 이력(SCD) 관리** |
| ETL/ELT 파이프라인 | 다양한 원천 시스템에서 데이터를 추출(Extract), 변환(Transform), **DW로 적재(Load)** |
| 데이터 마트 (Data Mart) | 특정 부서(마케팅, 재무 등)의 특화된 목적을 위해 **DW에서 요약 가공된 서브셋** |

#### 한줄 요약

- 사실 테이블, 차원 테이블, ETL 파이프라인, 데이터 마트가 결합하여 통합 분석 환경을 제공

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DW 데이터 적재 5단계 파이프라인**: CDC 데이터 추출 $\to$ 코드 표준화 $\to$ Fact/Dim 적재 $\to$ 마트 집계 $\to$ BI 대시보드 서빙.

</details>

```text
[ 데이터 웨어하우스 ETL 및 분석 서빙 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 운영계 원천 시스템 데이터 추출(CDC) │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 공통 코드 변환 및 품질 정제(Staging)│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. Fact Table 및 Dimension Table 적재  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 부서별 Data Mart 및 집계 뷰 생성    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. BI 대시보드 및 다차원 OLAP 서빙     │
 └───────────────────────────────────────┘
```

### 동작 원리

1. 데이터 추출: 원천 OLTP 데이터베이스로부터 배치 ETL 또는 CDC(Change Data Capture)를 통해 변경 이력을 추출.
2. 품질 정제: 스테이징 영역에서 전사 공통 코드 표준화, 결측치 보정, 중복 제거 등 데이터 클렌징을 수행.
3. DW 적재: 확정된 Grain(데이터 입도)과 SCD Type 2 정책에 따라 Fact 테이블과 Dimension 테이블에 데이터를 적재.
4. 마트 집계: 쿼리 속도 가속을 위해 주제별 Data Mart 및 사전 집계(Aggregation) 뷰를 구축.
5. BI 서빙: Tableau, PowerBI, SQL 클라이언트를 통해 경영진과 분석가에게 다차원 리포트를 제공.

#### 한줄 요약

- 데이터 추출 $\to$ 정제 표준화 $\to$ Fact/Dim 적재 $\to$ 마트 집계 $\to$ BI 서빙의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **스타 스키마 vs 스노우플레이크 스키마**: 차원 테이블을 비정규화하여 조인을 최소화한 스타 스키마와 차원 테이블을 3NF로 정규화한 스노우플레이크 스키마.

</details>

| 구분 | 스타 스키마 (Star Schema) | 스노우플레이크 스키마 (Snowflake Schema) |
|:---|:---|:---|
| **적용 기준** | 쿼리 단순성 및 고속 OLAP 조회가 최우선인 환경 | 차원 속성의 중복 제거 및 엄격한 계층 구조 관리가 필요한 환경 |
| **핵심 특징** | **차원 테이블 비정규화, Fact-Dim 간 1단계 Direct 조인** | **차원 테이블 3NF 정규화, 다단계 계층 조인 구조** |
| **한계** | 차원 테이블 내 중복 데이터로 인한 저장 공간 낭비 | 복잡한 다단계 조인 연산으로 인한 쿼리 성능 저하 |

#### 한줄 요약

- 조회 속도와 단순성이 최우선이면 스타 스키마, 저장 공간 절약과 정규화가 목적이면 스노우플레이크를 채택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **열 지향 포맷(Columnar Parquet)**: 디스크 블록에 데이터를 행 단위가 아닌 컬럼 단위로 연속 저장하여 특정 열 집계 시 I/O를 획기적으로 줄이는 최적화.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수억 건 Fact 테이블 풀 스캔으로 인한 쿼리 타임아웃 | **날짜 기반 파티셔닝(Partition Key) 및 Columnar Parquet 포맷 적용** | 스캔 데이터량 90% 이상 절감 |
| 차원 속성 갱신 시 과거 분석 수치가 변조되는 왜곡 현상 | **SCD Type 2(신규 레코드 추가 + 유효기간 컬럼 부여) 이력 관리** | 과거 시점의 정확한 분석 일관성 보존 |
| 전사 공통 지표 정의 불일치로 인한 부서 간 수치 왜곡 | **시맨틱 레이어(Semantic Layer / Metric Layer) 표준화 거버넌스 수립** | 단일 진실 공급원(SSOT) 확립 |

#### 한줄 요약

- 열 지향 포맷, SCD Type 2 이력 관리, 시맨틱 레이어 표준화를 통해 신뢰성 높은 DW를 운영

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **모던 클라우드 DW(Modern Cloud DW)**: Snowflake, Google BigQuery, AWS Redshift처럼 컴퓨팅과 스토리지가 분리된 서버리스 클라우드 DW 체계.

</details>

- **데이터 웨어하우스**는 데이터 기반 의사결정을 지원하는 엔터프라이즈 데이터 아키텍처의 중심 축이며, 차원 모델링과 최신 클라우드 DW 기술을 결합하여 고성능 다차원 분석 플랫폼을 구축해야 함

#### 한줄 요약

- 4대 특성과 차원 모델링을 기반으로 신뢰할 수 있는 단일 진실 공급원(SSOT) 분석 인프라를 완성
