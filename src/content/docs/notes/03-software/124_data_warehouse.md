## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 웨어하우스(Data Warehouse)**: 여러 원천의 이력을 주제별 공통 업무 정의로 통합해 분석에 제공하는 저장소이다.

</details>

- 정의/개념: 여러 원천의 이력을 주제별 공통 업무 정의로 통합하는 **분석 저장소**
- 배경/필요성: 운영 데이터베이스 직접 집계는 **거래 성능 저하·지표 불일치** 유발

#### 한줄 요약
- 여러 부서의 장부를 같은 항목표와 시간축으로 다시 묶어 하나의 보고서를 만드는 분석 창고이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **사실·차원 모델**: 측정 사건과 설명 속성을 분리해 대량 집계와 시계열 분석을 지원하는 모델이다.
- **주제 지향 통합**: 원천별 코드·단위·키를 고객·상품·매출 같은 공통 업무 주제로 통일하는 특성이다.
- **시계열 이력 보존**: 기준 시점과 유효 기간을 유지해 과거 당시의 상태로 분석하게 하는 특성이다.

</details>

- 원천별 코드·단위·키를 공통화하는 **주제 지향 통합**
- 기준 시점과 유효 기간을 유지하는 **시계열 이력 보존**
- **사실·차원 모델**과 열 지향 저장을 통한 대량 집계 최적화

#### 한줄 요약
- 데이터 웨어하우스는 여러 부서가 같은 지표 정의를 쓰게 하지만 원천 적재가 늦으면 보고서의 최신 시점도 늦어짐

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **사실 테이블**: 업무 사건의 측정값·시점·차원 키를 저장하는 구성요소이다.
- **원천·스테이징 영역**: 원천 스냅숏과 변경분을 정제 전 형태로 임시 보관하는 영역이다.
- **추출·변환·적재(Extract, Transform, Load, ETL)·품질 검사**: 원천 데이터를 추출해 공통 코드로 바꾸고 적재하면서 중복·누락을 검사하는 과정이다.
- **차원 테이블**: 고객·상품 같은 설명 속성과 유효 기간별 변경 이력을 저장하는 구성요소이다.
- **의미 계층·데이터 마트**: 승인된 업무 지표와 조회 권한을 사용자·부서별 분석 영역에 제공하는 계층이다.

</details>

```mermaid

    block:DW["데이터 웨어하우스"]

        S["원천·스테이징 영역"]

```

| 구성요소 | 책임 |
|:---|:---|
| 원천·스테이징 영역 | 원천별 **스냅숏·변경분** 임시 보관 |
| 추출·변환·적재(Extract, Transform, Load, ETL)·품질 검사 | 코드 표준화와 **중복·누락** 검사 |
| 사실 테이블 | 업무 사건의 **측정값·시점·차원 키** 저장 |
| 차원 테이블 | 설명 속성과 **변경 이력** 저장 |
| 의미 계층·데이터 마트 | 공통 **업무 지표·조회 권한** 제공 |

#### 한줄 요약

- 원천 보관함, 정제소, 측정 장부, 분류표, 공통 지표 화면으로 구성된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **2. 차원 이력·대체키**: 업무 기준정보의 유효 기간을 보존하고 사실 데이터와 연결할 내부 키를 만드는 단계이다.
- **추출·변환·적재(Extract, Transform, Load, ETL)**: 원천 스냅숏·변경분을 정제해 사실·차원 테이블에 적재하는 흐름이다.
- **비즈니스 인텔리전스(Business Intelligence, BI) 사용자**: 의미 계층의 승인 지표와 차원으로 분석 질의를 수행하는 사용자이다.
- **1. 스냅숏·변경분**: 기준 시점의 전체 상태와 이후 증분 범위를 고정한 원천 데이터이다.
- **3. 사실 측정값·차원 키**: 업무 사건의 값·시점과 당시 유효한 차원 버전을 연결한 데이터이다.
- **4. 승인 지표·차원 질의**: 공통 계산식과 분류 정의를 사용해 일관된 집계를 요청하는 질의이다.

</details>

```mermaid
sequenceDiagram
    participant S as 원천
    participant E as ETL·품질
    participant W as 웨어하우스
    participant M as 의미 계층
    participant B as BI 사용자
    S->>E: 1. 스냅숏·변경분
    E->>W: 2. 차원 이력·대체키
    W-->>E: 대체키·품질 결과
    E->>W: 3. 사실 측정값·차원 키
    W-->>E: 적재 건수·오류 반환
    B->>M: 분석 질의
    M->>W: 4. 승인 지표·차원 질의
    W-->>M: 집계 데이터
    M-->>B: 지표 집계 결과
```

**동작 원리**

1. **스냅숏·변경분**: 기준 시점과 증분 범위를 고정해 원천 데이터 수집
2. **차원 이력·대체키**: 업무 기준정보의 유효 기간을 보존하고 연결 키 생성
3. **사실 측정값·차원 키**: 검증된 차원 버전과 측정값·발생 시점 연결
4. **승인 지표·차원 질의**: 공통 계산식과 차원 정의로 일관된 집계 수행

#### 한줄 요약

- 서로 다른 이름표를 공통 분류표에 맞춘 뒤 거래 이력을 쌓아 같은 매출 지표를 제공한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 웨어하우스**: 공통 지표를 기준으로 여러 원천의 통합 이력을 분석하는 저장소이다.
- **온라인 트랜잭션 처리 데이터베이스(Online Transaction Processing Database, OLTP DB)**: 짧은 업무 거래의 현재 상태와 무결성을 처리하는 운영 저장소이다.
- **데이터 레이크(Data Lake)**: 정형·반정형·비정형 원시 데이터를 객체 파일로 넓게 보존하는 저장소이다.

</details>

| 분석 저장소 | 데이터 웨어하우스 | 온라인 트랜잭션 처리 데이터베이스(Online Transaction Processing Database, OLTP DB) | 데이터 레이크 |
|:---|:---|:---|:---|
| 적용 기준 | 공통 지표 기반 **통합 이력 분석** | 짧은 거래의 **현재 상태 처리** | 다양한 **원시 데이터 보존** |
| 핵심 특징 | **사실·차원 모델·열 저장** | 정규화 행과 **트랜잭션 인덱스** | 객체 파일과 **읽기 시점 스키마** |
| 한계 | **적재 지연·차원 모델** 설계 비용 | 분석 부하로 **거래 성능 저하** | **품질·발견성·작은 파일** 관리 부담 |


#### 한줄 요약

- 온라인 트랜잭션 처리는 지금 거래를 처리하고 웨어하우스는 정리된 이력을 분석하며 레이크는 원본을 넓게 보관한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **이력 왜곡**: 과거 사건을 최신 분류값으로 해석해 당시의 업무 상태가 바뀌는 문제이다.
- **사실 그레인(Fact Grain)**: 사실 테이블 한 행이 나타내는 최소 업무 사건과 측정 단위이다.
- **느리게 변경되는 차원(Slowly Changing Dimension, SCD)·유효 기간**: 차원 속성 변경을 버전과 적용 기간으로 보존해 과거 사실을 당시 상태에 연결하는 설계이다.
- **지표 공식·필터·소유자**: 공통 지표의 계산식과 포함 조건 및 정의 책임자를 등록한 거버넌스 정보이다.
- **원천 대사·오류 격리**: 원천과 적재 건수·합계를 비교하고 잘못된 레코드를 별도 보관해 재처리하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 한 행의 업무 사건이 다르면 **중복 집계** 발생 | 최소 측정 단위인 **사실 그레인** 명시 | 사실 테이블의 **행 의미** 통일 |
| 현재 차원값으로 과거 사실을 연결하면 **이력 왜곡** 발생 | **느리게 변경되는 차원(Slowly Changing Dimension, SCD)·유효 기간** 기반 차원 이력 설계 | 사실 발생 당시의 **차원 상태** 보존 |
| 부서별 계산식·필터가 다르면 **지표 불일치** 발생 | **지표 공식·필터·소유자** 등록 | 조직별 **지표 계산** 일치 |
| 원천 건수와 적재 건수가 다르면 **누락·중복** 은폐 | **원천 대사·오류 격리** 적용 | 적재 오류의 **탐지·재처리** 가능 |

#### 한줄 요약

- 한 행이 무엇을 뜻하고 어느 시점의 분류를 쓰는지 정해야 과거 매출이 바뀌지 않는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **사실 그레인·차원 이력**: 웨어하우스에서 한 행의 의미와 과거 분류 상태를 고정하는 두 설계 기준이다.

</details>

- 공통 지표와 이력 분석이 필요하면 **사실 그레인·차원 이력**을 고정한 웨어하우스 구축

#### 한줄 요약

- 같은 숫자의 뜻·출처·기준 시점을 모두 설명할 수 있어야 믿을 수 있는 분석 저장소이다.
