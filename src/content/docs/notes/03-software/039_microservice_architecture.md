## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **마이크로서비스 아키텍처(Microservice Architecture, MSA)**: 업무별 서비스가 데이터와 배포 경계를 독립적으로 소유하는 분산 아키텍처이다.
- **장애 격리(Fault Isolation)**: 실패한 서비스의 영향이 다른 서비스로 연쇄 전파되지 않도록 제한하는 성질이다.

</details>

- 정의/개념: **MSA**는 업무별 서비스가 데이터•배포 경계를 소유하는 분산 아키텍처이다.
- 배경/필요성: 단일 배포 구조로는 업무별 변경•확장과 **장애 격리**가 어렵다.

#### 한줄 요약

- **MSA**는 업무별 데이터•배포 경계를 독립 서비스로 분리한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **서비스 경계(Service Boundary)**: 하나의 업무•데이터와 담당 팀의 책임을 함께 묶는 서비스 단위이다.
- **버전된 계약(Versioned Contract)**: API•이벤트에 버전을 부여해 생산자와 소비자의 변경 시점이 달라도 호환되게 하는 규칙이다.
- **부분 장애(Partial Failure)**: 분산 시스템의 일부 서비스나 네트워크만 실패하고 나머지는 계속 동작하는 상태다.
- **타임아웃(Timeout)**: 원격 응답을 기다리는 시간을 제한하는 제어이다.
- **격리(Isolation)**: 실패 자원의 영향 범위를 분리하는 제어이다.
- **복구(Recovery)**: 재시도와 대체 및 재시작으로 기능을 회복하는 처리이다.

</details>

- 업무•데이터•배포 책임을 **서비스 경계**로 정렬한다.
- **버전된 계약**으로 내부 구현을 숨긴다.
- **부분 장애**를 전제로 **타임아웃**, **격리**, **복구**를 설계한다.

#### 한줄 요약

- **서비스 경계**, **버전된 계약**, **부분 장애** 대응을 정렬한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **응용 프로그래밍 인터페이스 게이트웨이(Application Programming Interface Gateway, API Gateway)**: 외부 요청을 내부 서비스로 라우팅하고 공통 정책을 적용하는 진입점이다.
- **데이터 소유권(Data Ownership)**: 특정 데이터를 변경할 권한과 책임을 하나의 서비스에만 부여하는 원칙이다.
- **이벤트 브로커(Event Broker)**: 생산자가 발행한 비동기 이벤트를 구독 서비스로 라우팅하는 중개자이다.
- **관측 플랫폼(Observability Platform)**: 로그•메트릭•분산 추적을 연결해 서비스 상태와 요청 경로를 분석하는 도구이다.

</details>

```text
               [API 게이트웨이]
                  /         \
 [주문 서비스•소유 데이터] [결제 서비스•소유 데이터]
                  \         /
               [이벤트 브로커]
                      |
                [관측 플랫폼]
```

선의 의미: 위 가지는 게이트웨이의 서비스 진입 경계, 가운데 선은 두 서비스의 공통 관측 경계, 아래 가지는 두 서비스가 공유하는 비동기 이벤트 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| API 게이트웨이 | **API 게이트웨이**가 외부 요청 라우팅•공통 정책 적용 |
| 주문 서비스•소유 데이터 | 주문 서비스가 **데이터 소유권** 보유 |
| 결제 서비스•소유 데이터 | 결제 서비스가 데이터 소유권 보유 |
| 이벤트 브로커 | **이벤트 브로커**가 서비스 간 비동기 이벤트 라우팅 |
| 관측 플랫폼 | **관측 플랫폼**이 로그•메트릭•분산 추적 연결 |

#### 한줄 요약

- **API 게이트웨이**, **데이터 소유권**, **이벤트 브로커**, **관측 플랫폼**이 서비스 경계를 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **외부 요청 라우팅**: 게이트웨이가 인증•한도 정책을 적용하고 소유 서비스로 요청을 보내는 단계이다.
- **소유 서비스 로컬 처리**: 서비스가 자신의 업무 규칙과 데이터 변경을 로컬 트랜잭션으로 수행하는 단계이다.
- **서비스 간 계약 선택**: 즉시 결과가 필요한지 독립 전파가 필요한지에 따라 API 또는 이벤트를 고르는 단계이다.
- **동기 API 협업**: 대상 서비스 응답이 필요한 작업을 버전된 요청•응답 계약으로 처리하는 단계이다.
- **비동기 이벤트 협업**: 이벤트를 브로커에 발행해 구독 서비스가 독립적으로 처리하게 하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 외부 서비스 요청           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 외부 요청 라우팅        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 소유 서비스 로컬 처리   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 서비스 간 계약 선택     │
└───────┬──────────────────────┘
        ├─ 즉시 응답 필요
        │      └─▶ [4. 동기 API 협업]
        │
        └─ 독립 전파 필요
               └─▶ [5. 비동기 이벤트 협업]

각 대상 서비스는 자신의 데이터만 변경
```

### 동작 원리

1. **외부 요청 라우팅**으로 공통 정책을 적용하고 소유 서비스를 선택한다.
2. **소유 서비스 로컬 처리**로 업무•데이터 변경을 경계 안에서 수행한다.
3. **서비스 간 계약 선택**으로 응답 결합도에 따라 API•이벤트를 결정한다.
4. **동기 API 협업**으로 버전된 요청•응답 계약을 호출한다.
5. **비동기 이벤트 협업**으로 브로커를 통해 독립적으로 소비한다.

#### 한줄 요약

- **소유 서비스 로컬 처리**와 **동기 API 협업**•**비동기 이벤트 협업**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **모듈러 모놀리스(Modular Monolith)**: 하나의 애플리케이션으로 배포하면서 내부 업무를 모듈 경계로 분리한 구조이다.
- **원격 통신(Remote Communication)**: 다른 프로세스나 장비의 서비스에 네트워크로 요청•이벤트를 전달하는 통신이다.
- **운영 자동화(Operations Automation)**: 서비스별 빌드•배포•확장•관측•복구를 자동화해 독립 배포 비용을 줄이는 역량이다.
- **분산 일관성(Distributed Consistency)**: 여러 서비스가 각자 소유한 데이터의 변경을 메시지와 보상 절차로 정해진 관계에 수렴시키는 성질이다.
- **확장 결합(Scaling Coupling)**: 일부 기능만 부하가 늘어도 전체 애플리케이션을 함께 확장해야 하는 제약이다.

</details>

| 서비스 구조 | 마이크로서비스 | 모듈러 모놀리스 |
|:---|:---|:---|
| 적용 기준 | 독립 변화•**운영 자동화** 역량 | 유사한 변경 주기•단순 운영 |
| 핵심 특징 | 독립 배포•소유 데이터•**원격 통신** | **모듈러 모놀리스**의 단일 배포•모듈 경계•내부 호출 |
| 한계 | **분산 일관성**•부분 장애 | 전체 배포•**확장 결합** |

> 요약: 독립 배포 이익과 분산 운영 비용으로 구조를 선택한다.

#### 한줄 요약

- 독립 배포는 MSA, 단순 운영은 **모듈러 모놀리스**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **분산 모놀리스(Distributed Monolith)**: 서비스를 나눴지만 강하게 결합돼 함께 변경•배포해야 하는 구조이다.
- **트랜잭셔널 아웃박스(Transactional Outbox)**: 업무 데이터와 이벤트를 한 로컬 트랜잭션에 저장한 뒤 브로커로 전달하는 방식이다.
- **멱등성(Idempotency)**: 같은 이벤트나 요청을 여러 번 처리해도 최종 결과가 한 번 처리한 것과 같은 성질이다.
- **회로 차단기(Circuit Breaker)**: 원격 호출 실패가 기준을 넘으면 호출을 잠시 중단해 장애 전파를 막는 제어이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 응답 시간•가용성 등 서비스 품질에 대해 달성하기로 정한 측정 목표이다.
- **로그(Log)**: 서비스 사건과 오류를 시간순으로 기록한 신호이다.
- **메트릭(Metric)**: 서비스 상태를 나타내는 수치 시계열 신호이다.
- **분산 추적(Distributed Tracing)**: 서비스 간 요청 경로를 연결한 관측 신호이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기술 계층만 따라 서비스를 세분화 | 업무 규칙•데이터•팀 책임으로 경계 검증 | **분산 모놀리스** 방지 |
| 여러 서비스가 같은 저장소를 직접 갱신 | 데이터 소유권 단일화와 API•이벤트 협업 | 독립 변경•배포 확보 |
| 저장 성공 후 이벤트 발행 실패•중복 | **트랜잭셔널 아웃박스**•**멱등성** 적용 | 데이터•이벤트 정합성 향상 |
| 동기 호출 연쇄로 지연•장애 전파 | 타임아웃•**회로 차단기**와 비동기 전환 | 부분 장애 영향 제한 |
| 서비스 수 증가와 운영 자동화 부족 | **SLO**•**로그**•**메트릭**•**분산 추적** 제공 | 운영 복잡도 통제 |

#### 한줄 요약

- **트랜잭셔널 아웃박스**, **회로 차단기**, **SLO**, **분산 추적**으로 운영한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **독립 배포 이익**: 한 업무의 변경•확장•복구를 다른 서비스 배포와 분리해 얻는 효과이다.
- **분산 비용**: 원격 통신•부분 장애•데이터 일관성•관측 자동화에 추가로 드는 비용이다.
- **서비스 구조 선택 기준**: 독립 배포 이익과 분산 비용을 비교해 MSA와 모듈러 모놀리스 중 적합한 구조를 고르는 기준이다.

</details>

- **독립 배포 이익**이 **분산 비용**보다 크면 **MSA**, 아니면 **모듈러 모놀리스**를 선택하는 것이 **서비스 구조 선택 기준**이다.

#### 한줄 요약

- 독립 배포 이익과 분산 비용을 함께 평가하는 것이 핵심이다.
