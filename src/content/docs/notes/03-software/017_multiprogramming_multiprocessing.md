## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Multiprogramming(다중프로그래밍)**: 단일 프로세서 환경에서 복수의 프로그램을 메모리에 동시에 적재하고, I/O 대기 시간 동안 CPU를 다른 프로세스로 문맥 전환하여 CPU 유휴 시간을 최소화하는 시분할 실행 기법.
- **Multiprocessing(다중처리)**: 2개 이상의 물리적 CPU 코어를 장착하여 복수의 명령어 스트림을 물리적으로 완전히 동시에 병렬(Parallel) 실행하는 시스템 처리 기법.

</details>

- 정의/개념: 단일 코어 기반 I/O 유휴 시간 중첩 제어로 CPU 이용률을 극대화하는 **다중프로그래밍(Multiprogramming)** 과 복수 물리 코어 기반 동시 병렬 연산을 수행하는 **다중처리(Multiprocessing)** 아키텍처
- 배경/필요성: 단일 프로세서의 I/O 블로킹 대기 시간에 따른 **CPU 연산 자원 낭비 해소 및 대규모 워크로드 처리량 한계 극복** 필요

#### 한줄 요약

- 단일 CPU에서 교대 실행으로 유휴 시간을 없애는 다중프로그래밍과 복수 코어로 물리적 병렬 연산을 수행하는 다중처리

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Interleaving(교대 실행/인터리빙)**: 단일 코어 상에서 여러 작업의 시간 슬라이스를 미세하게 분할하여 번갈아 가며 실행하는 시분할 동시성(Concurrency) 기법.
- **Parallel Execution(병렬 실행)**: 복수의 물리적 실행 유닛(코어)에서 같은 시점에 서로 다른 명령어를 실제로 동시 실행하는 기법.

</details>

- **다중프로그래밍**: 단일 CPU 상에서 I/O 발생 시 다른 프로세스로 신속히 전환하는 **인터리빙(Interleaving) 기반 동시성(Concurrency)**
- **다중처리**: 복수 물리 코어 상에서 독립적인 명령어 파이프라인을 구동하는 **하드웨어 레벨 병렬성(Parallelism)**
- 다중처리 환경에서는 코어 간 공유 메모리 동기화, 캐시 일관성(Cache Coherence) 유지 및 버스 대역폭 관리 필요

#### 한줄 요약

- **시분할 인터리빙 기반 동시성(다중프로그래밍) vs 멀티코어 물리 동시 실행 기반 병렬성(다중처리)**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SMP(Symmetric Multiprocessing, 대칭형 다중처리)**: 모든 CPU 코어가 단일 공유 메모리와 I/O 버스를 대등하게 접근하고 동일한 운영체제 인스턴스에 의해 제어되는 구조.
- **Amdahl's Law(암달의 법칙)**: 프로세서 수를 무한히 늘려도 프로그램 내 직렬 처리 구간(Serial Fraction)의 비율에 의해 시스템 최대 가속비(Speedup)가 제한된다는 법칙.

</details>

```text
[ 다중프로그래밍 vs 다중처리 아키텍처 비교 ]
 ┌─ [ 다중프로그래밍: 단일 코어 시분할 ] ────────┐
 │   [ 작업 집합 (A, B, C) ] ──► [ 단일 CPU 코어 ] (시간 분할 인터리빙)
 └───────────────────────────────────────────────┘

 ┌─ [ 다중처리: 멀티코어 물리 병렬 ] ───────────┐
 │   [ 작업 집합 ] ──► [ OS 스케줄러 ]
 │                          ├──► [ CPU 코어 1 ] (태스크 A 실행)
 │                          └──► [ CPU 코어 2 ] (태스크 B 실행)
 │                                    │
 │                           [ 공유 메모리 (SMP) ]
 └───────────────────────────────────────────────┘
```

선의 의미: 다중프로그래밍은 단일 코어에 시분할 교대 할당되고, 다중처리는 스케줄러가 복수 물리 코어에 병렬 할당하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 작업 준비 큐(Ready Queue) | 메모리에 적재되어 CPU 디스패치를 대기 중인 프로세스 목록 관리 |
| OS 스케줄러 | 스케줄링 정책에 따라 작업을 적합한 CPU 코어에 배정 및 문맥 전환 제어 |
| CPU 코어(Core 1 ~ N) | 할당된 프로세스의 기계어 명령어를 인출·해독·실행하는 물리 연산 장치 |
| 공유 메모리/캐시 계층 | SMP 구조에서 코어 간 일관된 데이터 공유 및 동기화 인터페이스 제공 |

#### 한줄 요약

- **단일 코어 시분할 큐 vs 멀티코어 분배 스케줄러·SMP 공유 메모리 및 캐시 일관성 버스**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Context Switch Overhead(문맥 전환 오버헤드)**: 현재 프로세스의 CPU 레지스터 상태를 PCB에 저장하고 새 프로세스의 PCB 상태를 복원하는 과정에서 소모되는 CPU 사이클.

</details>

```text
[ 다중프로그래밍과 다중처리의 실행 흐름 비교 ]

 1. 다중프로그래밍 (단일 코어 동시성)
    [ 태스크 A 실행 ] ──(I/O 요청 블로킹)──► [ 문맥 전환 (Context Switch) ]
                                                       │
    [ 태스크 A I/O 완료 후 Ready ] ◄── [ 태스크 B 실행 (CPU 유휴 방지) ]

 2. 다중처리 (멀티코어 병렬성)
    [ 태스크 A, B 동시 인입 ]
              │
    ┌─────────┴─────────┐
    ▼                   ▼
 [ 코어 1: 태스크 A ]   [ 코어 2: 태스크 B ]   (동일 시점 물리 병렬 실행)
```

**동작 원리**

1. **다중프로그래밍 인터리빙**: 실행 중인 프로세스가 디스크/네트워크 I/O를 요청하면 즉시 CPU를 반납하고 대기 상태로 전환되며, 스케줄러가 준비 큐의 다른 프로세스를 디스패치하여 CPU 가동률 유지
2. **다중처리 병렬 배분**: 복수의 독립 작업이 인입되면 OS 스케줄러가 사용 가능한 개별 물리 코어에 작업을 즉시 분배하여 동시 실행
3. **자원 동기화 제어**: 다중처리 환경에서는 동시 접근에 따른 경쟁 상태를 방지하기 위해 하드웨어 원자적 명령어(Atomic CAS) 및 잠금 프로토콜 적용

#### 한줄 요약

- **I/O 블로킹 시 즉각 문맥 전환(다중프로그래밍)과 복수 코어 동시 분배 실행(다중처리)**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Multitasking vs Multithreading**: 멀티태스킹은 OS 차원에서 독립된 프로세스들을 시분할 실행하는 것이며, 멀티스레딩은 단일 프로세스 주소 공간 내에서 스레드들이 자원을 공유하며 병렬/동시 실행하는 기법.

</details>

| 비교 항목 | 다중프로그래밍 (Multiprogramming) | 시분할/멀티태스킹 (Multitasking) | 다중처리 (Multiprocessing) | 멀티스레딩 (Multithreading) |
|:---|:---|:---|:---|:---|
| 핵심 목적 | CPU 유휴 시간 최소화 | 대화형 응답성 극대화 | 연산 처리량(Throughput) 극대화 | 프로세스 내 자원 공유 및 경량 동시성 |
| 코어 자원 | **단일 코어** 중심 (I/O 전환) | **단일/멀티 코어** (타임 슬라이스) | **복수 물리 코어/CPU** 필수 | 단일/멀티 코어 상 스레드 실행 |
| 동시성 성격 | 시분할 동시성 (Concurrency) | 시분할 동시성 (Concurrency) | **물리적 병렬성 (Parallelism)** | 논리 동시성 및 물리 병렬성 |
| 주 병목 요인 | I/O 대기 및 메모리 부족 | 문맥 전환 오버헤드 | **캐시 일관성·메모리 버스 경합** | 임계 구역 동기화 락 경합 |

#### 한줄 요약

- 유휴 방지는 다중프로그래밍, 응답성은 멀티태스킹, 처리량 증대는 다중처리, 경량 공유는 멀티스레딩

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **False Sharing(거짓 공유)**: 서로 다른 코어가 독립적인 변수를 수정함에도 불구하고, 두 변수가 동일한 64바이트 캐시 라인에 위치하여 불필요한 캐시 라인 무효화 버스 트래픽이 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다중프로그래밍 정도(DOM) 과다로 인한 **메모리 부족 및 스레싱 발생** | 수용 제어(Admission Control) 및 **워킹 셋 기반 프로세스 수 제한** | 스왑 I/O 폭증 차단 및 CPU 이용률 보장 |
| 멀티코어 환경에서 독립 변수 동시 갱신 시 **거짓 공유(False Sharing) 발생** | 캐시 라인 패딩(Padding) 및 **`@Contended` 정렬 어노테이션** 적용 | 불필요한 캐시 라인 무효화 트래픽 및 버스 병목 제거 |
| 코어 수 증가에도 불구하고 **직렬 병목 구간(Amdahl's Law)으로 가속비 정체** | 락 프리(Lock-Free) 자료구조 도입 및 **직렬 임계 구역 최소화** | 병렬 확장성(Scalability) 극대화 |

#### 한줄 요약

- **수용 제어 기반 스레싱 방어·캐시 패딩 기반 거짓 공유 방지·락 프리 기반 직렬 병목 최소화**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Workload-Aware Architecture Selection**: I/O 집약도, 병렬화 가능 비율, 하드웨어 비용을 종합 고려하여 최적의 동시성/병렬성 처리 아키텍처를 결정하는 설계 기준.

</details>

- 대규모 엔터프라이즈 시스템 구축 시 **I/O 바운드 작업은 비동기 이벤트 루프 기반 다중프로그래밍/멀티태스킹, CPU 바운드 대규모 연산은 멀티소켓 NUMA 다중처리 아키텍처** 복합 채택

#### 한줄 요약

- **워크로드 특성에 따른 시분할 동시성과 물리 병렬 처리의 최적 결합**을 통한 시스템 성능 극대화
