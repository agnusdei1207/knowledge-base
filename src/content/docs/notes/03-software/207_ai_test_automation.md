## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AI 기반 테스트 자동화 (AI Test Automation)**: 소스코드, 요구사항, 변경 이력을 LLM 및 머신러닝으로 분석하여 테스트 케이스 생성, 회귀 테스트 선별(Test Selection), 실패 군집화를 지능화하는 기술.
- **Test Oracle (테스트 오라클)**: 테스트 실행 결과가 참(Pass)인지 거짓(Fail)인지 판정하는 기준, 기대값 및 검증 규칙.

</details>

- 정의/개념: 소스코드 변경과 요구사항을 기반으로 **테스트 케이스 생성, 회귀 테스트 선별, 실패 원인 분석을 지능화하는 AI 엔지니어링 기술**
- 배경/필요성: 전수 회귀 테스트 실행에 따른 **CI/CD 파이프라인 지연 병목, 수작업 테스트 스크립트 작성 비용 과다 및 플래키(Flaky) 테스트로 인한 빌드 신뢰도 저하 한계**

#### 한줄 요약
- AI 기반 테스트 생성과 변경 영향도 선별 및 오라클 검증을 통해 CI/CD 파이프라인의 품질과 속도를 동시에 확보한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Test Impact Analysis (TIA, 테스트 영향도 분석)**: 커밋된 코드 변경점과 의존성 그래프를 분석하여 연관된 최소한의 테스트 스위트만을 선별 실행하는 기법.
- **Mutation Score (변이 점수)**: 인위적으로 주입한 코드 결함(Mutant)을 테스트 케이스가 얼마나 검출해 내는지 평가하는 테스트 신뢰도 지표.

</details>

- 코드 변경 및 호출 그래프를 분석하여 실행 대상을 압축하는 **테스트 영향도 분석(TIA)**
- LLM을 활용하여 복잡한 비즈니스 경계값 및 엣지 케이스를 도출하는 **테스트 시나리오 자동 생성**
- 유사한 실패 로그와 스택 트레이스를 묶어 원인을 규명하는 **실패 군집화(Failure Clustering)**

#### 한줄 요약
- 테스트 영향도 선별, 시나리오 자동 생성, 실패 군집화를 통해 테스트 효율과 커버리지를 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AI 테스트 자동화 4대 핵심 구조**: Test Generator(LLM 기반 생성), Regression Selector(변경 영향 선별), Oracle Gate(정답/보안 검증), Isolated Sandbox(격리 실행기).

</details>

```text
[AI 테스트 자동화 구성]
|-- 테스트 생성기
|-- 회귀 선별기
|-- 오라클 게이트
|-- 격리 실행기
`-- 품질 평가기
```

선의 의미: 계층 및 요구사항과 코드 변경을 분석하여 테스트를 생성/선별하고 오라클 게이트를 거쳐 샌드박스에서 실행 후 변이 점수를 평가하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| 테스트 생성기 (Generator) | 요구사항과 코드 변경점(Diff)을 입력받아 경계값 및 예외 시나리오 단위/통합 테스트 생성 | LLM 프롬프팅 |
| 회귀 선별기 (Selector) | 호출 그래프와 코드 의존성을 분석하여 영향받는 최소한의 테스트 스위트 선별(TIA) | ML 기반 선별 |
| 오라클 게이트 (Gate) | 생성된 테스트의 기대값(Oracle), 보안 취약점, 중복성을 규칙 기반으로 검증 및 승인 | 정답 검증 게이트 |
| 격리 실행기 (Runner) | 승인된 테스트를 도커 샌드박스 환경에서 안전하게 병렬 실행하고 로그 수집 | 격리 환경 실행 |
| 품질 평가기 (Evaluator) | 인위적 결함 주입을 통한 Mutation Score 측정 및 Flaky(불안정) 테스트 자동 탐지 | 테스트 신뢰도 평가 |

#### 한줄 요약
- 선별기가 실행량을, 생성기가 작성 공수를 줄이는 대신 오라클 게이트와 품질 평가기가 그 산출물을 검증하므로, 자동화가 얻은 속도가 판정 신뢰도를 잠식하지 않는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **AI 테스트 자동화 5단계**: 변경 코드 분석 $\to$ 영향도 기반 선별 $\to$ 엣지 시나리오 생성 $\to$ 격리 샌드박스 실행 $\to$ 변이 점수 피드백.

</details>

```text
개발자 소스코드 Git Commit & PR 제출
        │
   1. [변경 코드 분석] Git Diff와 정적 분석기로 수정된 함수 및 호출 의존성 그래프 도출
        │
   2. [영향도 기반 선별] 전체 10,000개 테스트 중 수정 영향 범위 내 300개 회귀 테스트 선별
        │
   3. [엣지 시나리오 생성] LLM이 신규 추가된 비즈니스 로직에 대해 10개 예외 테스트 자동 생성
        │
   4. [오라클 검증 및 격리 실행] 정답 오라클 검증 통과 후 도커 격리 샌드박스에서 병렬 실행
   ┌────┴───────────────────────────┐
  테스트 통과                       실패 감지
   │                                 │
5A. [Mutation Score 평가]           5B. [실패 군집화 및 원인 분석]
   변이 점수 90% 이상 시 CI 통과        동일 스택 에러 군집화 후 PR 리포트
   │                                 │
   └────┬────────────────────────────┘
        ▼
   CI 파이프라인 고품질 자동 배포 승인
```

#### 한줄 요약
- 영향도 선별이 앞에 놓여 실행 비용이 전체 규모가 아니라 변경 범위에 비례하게 되지만, 선별이 과하면 절감한 시간만큼 회귀 결함을 놓칠 위험을 떠안는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Rule 기반 vs ML 기반 vs 생성형 AI**: 정적 스크립트(Rule), 통계적 선별(ML), 문맥 기반 시나리오 생성(생성형 AI).

</details>

| 비교 항목 | 규칙 기반 (Rule-based) | 머신러닝 기반 (ML-based) | 생성형 AI 기반 (GenAI) |
|:---|:---|:---|:---|
| 핵심 적용 역할 | 결정론적 반복 회귀 테스트 실행 | 테스트 선별(TIA), 결함 발생 위치 예측 | 신규 테스트 코드 및 경계값 시나리오 생성|
| 핵심 강점 | 높은 오라클 신뢰성, 재현성 100% | 과거 이력 기반 테스트 실행 시간 단축 | 자연어 요구사항 문맥 기반 테스트 확장 |
| 주요 한계 | 유지보수 공수 과다, 엣지 케이스 누락 | 초기 대량의 테스트 실행 이력 데이터 필요 | 환각(Hallucination), 불안정한 오라클 판정 |
| 최적 적용 대상 | 금융 회계 결제 등 정밀 핵심 도메인 | 수만 개 테스트를 가진 대규모 모놀리스 | 신규 기능 개발 및 경계 조건 탐색 |

#### 한줄 요약
- 정밀 판정은 Rule 기반, 실행 시간 단축은 ML 선별, 테스트 케이스 확장은 생성형 AI를 결합한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Flaky Test (불안정 테스트)**: 소스코드 변경이 없음에도 네트워크 타이밍이나 동시성 이슈로 인해 성공과 실패를 반복하는 비결정적 테스트.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| AI가 생성한 테스트의 기대값(Oracle) 오류로 인한 거짓 양성 | 규칙 기반 assertion 및 개발자 `Human-in-the-Loop` 교차 검증 | 오탐(False Positive) 100% 방지 |
| 소스코드 및 비즈니스 로직의 외부 퍼블릭 LLM 노출 보안 사고 | 사내 온프레미스 사설 LLM 구축 및 개인정보/코드 비식별화 | 기업 지적재산권(IP) 보호 |
| 타이밍 이슈로 간헐적 실패를 유발하는 **Flaky Test** 증가 | Mock 격리 및 3회 반복 재실행 검증 필터 | CI 빌드 신뢰도 확보 |
| 라인 커버리지 100% 달성에도 실제 비즈니스 버그 미탐지 | 인위적 결함을 주입하여 잡는 `Mutation Testing (변이 시험)` 병행 | 실질적 결함 탐지력 확보 |

#### 한줄 요약
- 네 대책은 생성형 자동화가 얻어 준 속도의 대가인 오탐·정보 유출·불안정성을 검증 절차와 격리 환경으로 되사는 선택이다.

## Ⅶ. 결론

- 애자일(Agile) 및 데브옵스(DevOps) 환경에서 배포 빈도를 극대화하면서도 소프트웨어 품질을 엄격히 방어하는 **가장 핵심적인 차세대 품질 엔지니어링(QE) 및 테스트 지능화 표준**으로 자리잡았으며, 실무 구축 시에는 **ML 기반 테스트 영향도 분석(TIA)을 통한 회귀 테스트 최적 선별, 사내 보안 격리 LLM을 활용한 경계 조건 테스트 자동 생성, 테스트 오라클 검증 및 Human-in-the-Loop 검토를 통한 오탐 방어, Mutation Testing을 통한 실질적 테스트 유효성 평가**를 결합하여 개발 생산성과 릴리즈 안정성을 완벽히 조화

#### 한줄 요약
- AI 기반 테스트 자동화는 테스트 케이스 생성, 영향도 선별, 실패 군집화를 통해 CI/CD 병목을 해소하고 결함 탐지력을 극대화하는 핵심 품질 혁신 기술이다.
