## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **확장형 애자일 프레임워크(Scaled Agile Framework, SAFe)**: 린•애자일 원칙을 가치 흐름과 전사 조직으로 확장한 프레임워크이다.
- **린•애자일(Lean•Agile)**: 가치 흐름의 낭비를 줄이고 짧은 증분 피드백으로 변화에 적응하는 원칙이다.

</details>

- 정의/개념: **SAFe**는 **린•애자일**을 전사 가치 흐름에 확장한 프레임워크이다.
- 배경/필요성: 독립 팀 계획만으로는 다수 팀의 의존성과 통합 일정을 조정하기 어렵다.

#### 한줄 요약

- **SAFe**는 전략•투자•팀 의존성을 **린•애자일** 원칙으로 정렬한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **애자일 릴리스 트레인(Agile Release Train, ART)**: 여러 팀을 공통 임무와 개발 주기로 묶은 장기 조직이다.
- **계획 주기(Planning Interval, PI)**: ART가 공통 목표를 수행하는 시간 단위이다.
- **가치 흐름(Value Stream)**: 아이디어와 투자를 고객 가치로 전환하는 개발 활동의 흐름이다.
- **포트폴리오 계층(Portfolio Level)**: 전략과 투자를 가치 흐름에 연결하는 계층이다.
- **프로그램 조정 계층(Program Level)**: 여러 팀의 목표와 일정 및 의존성을 맞추는 계층이다.

</details>

- **ART**와 **PI**로 다수 팀의 목표•의존성을 정렬한다.
- **가치 흐름**으로 전략•투자•제품 실행을 연결한다.
- **포트폴리오 계층**과 **프로그램 조정 계층**으로 대규모 실행을 통제한다.

#### 한줄 요약

- **ART**, **PI**, **가치 흐름**을 통한 다수 팀 정렬이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **린 포트폴리오 관리(Lean Portfolio Management, LPM)**: 기업 전략과 투자를 개발 가치 흐름에 연결하는 관리 방식이다.
- **개발 가치 흐름(Development Value Stream, DVS)**: 아이디어를 고객 가치로 전환하는 개발 활동의 흐름이다.
- **애자일 팀**: 반복마다 제품 증분을 개발하고 검증하는 실행 조직이다.

</details>

```text
[린 포트폴리오 관리]
          |
[개발 가치 흐름]
          |
[애자일 릴리스 트레인]
          |
[애자일 팀]
```

선의 의미: 린 포트폴리오 관리는 개발 가치 흐름의 전략과 투자를 관리하고, 개발 가치 흐름은 애자일 릴리스 트레인으로 구현되며, 릴리스 트레인은 여러 애자일 팀을 묶어 조정한다.

| 구성요소 | 책임 |
|:---|:---|
| 린 포트폴리오 관리 | **린 포트폴리오 관리**가 전략•투자 우선순위 관리 |
| 개발 가치 흐름 | **개발 가치 흐름**이 아이디어를 고객 가치로 전환 |
| 애자일 릴리스 트레인 | 여러 팀의 목표•의존성 정렬 |
| 애자일 팀 | **애자일 팀**이 반복별 증분 개발•검증 |

#### 한줄 요약

- **LPM**, **DVS**, **애자일 팀**의 계층 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **PI 계획(PI Planning)**: 참여 팀이 계획 주기의 목표•용량•의존성을 함께 정렬하는 활동이다.
- **시스템 데모(System Demo)**: 여러 팀이 통합한 결과를 하나의 시스템 수준에서 검토하는 이벤트이다.
- **통합 증분(Integrated Increment)**: 여러 팀 결과를 공동 시스템에서 결합•검증한 결과이다.
- **검사•적응(Inspect and Adapt)**: 시스템 결과와 흐름 지표를 보고 다음 PI의 개선 방향을 정하는 활동이다.
- **전략•투자 우선순위**: 가치 흐름 목표와 투자 순서를 정하는 단계이다.
- **PI 목표•의존성 정렬**: 팀별 용량•위험•책임자를 합의해 공통 계획을 만드는 단계이다.
- **팀 증분•시스템 통합**: 팀별 결과를 공동 시스템에 결합하고 통합 증분으로 검증하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 1. 전략•투자 우선순위      │◀──────────────┐
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 2. PI 목표•의존성 정렬     │               │
│ 용량•위험•책임자 합의      │               │
└──────────────┬───────────────┘               │
               ▼                               │
╔══════════════════════════════╗               │
║ 반복: PI 내부 팀 반복      ║               │
║ 3. 팀 증분•시스템 통합     ║               │
╚══════════════╤═══════════════╝               │
               ▼                               │
┌──────────────────────────────┐               │
│ 4. 시스템 데모             │               │
│ 통합 가치•흐름 지표 검토   │               │
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 5. 검사•적응               │───────────────┘
│ 다음 PI 목표•개선 조정     │
└──────────────────────────────┘
```

### 동작 원리

1. **전략•투자 우선순위**로 가치 흐름 목표를 결정한다.
2. **PI 계획**에서 **PI 목표•의존성 정렬**로 용량•위험•책임자를 합의한다.
3. **팀 증분•시스템 통합**으로 반복 결과를 **통합 증분**에 반영한다.
4. **시스템 데모**로 여러 팀의 통합 결과를 검토한다.
5. **검사•적응**으로 가치•위험 피드백을 다음 PI에 반영한다.

#### 한줄 요약

- **PI 계획**부터 **검사•적응**까지의 피드백 순환이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **스크럼(Scrum)**: 단일 팀이 스프린트마다 사용 가능한 제품 증분을 만들고 검토하는 프레임워크이다.
- **조정 계층**: 여러 팀의 목표•일정•의존성을 맞추기 위해 추가되는 포트폴리오•프로그램 관리 층이다.

</details>

| 애자일 적용 규모 | SAFe | 단일 팀 스크럼 |
|:---|:---|:---|
| 적용 기준 | 공동 가치 흐름•팀 간 의존성 큼 | 독립 제품•팀 내부 조정 |
| 핵심 특징 | 가치 흐름•ART•PI 정렬 | **스크럼**의 제품•단일 팀•스프린트 |
| 한계 | **조정 계층**에 따른 의사결정 지연 | 팀 간 의존성 누락 |

> 요약: SAFe는 가치 흐름과 다수 팀, 스크럼은 단일 팀을 정렬한다.

#### 한줄 요약

- 팀 의존성이 크면 **SAFe**, 독립 팀은 스크럼이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **흐름 지표(Flow Metric)**: 대기•처리 시간, 진행 중 작업 수, 완료율로 가치 전달 흐름을 측정하는 지표이다.
- **작업 진행 한도(Work-in-progress Limit)**: 동시에 진행하는 작업 수를 제한해 대기와 미완료 누적을 줄이는 기준이다.
- **가드레일(Guardrail)**: 팀의 자율 결정 범위와 넘지 말아야 할 비용•위험 기준이다.
- **가치 흐름•의존성 지도화**: 아이디어부터 고객 가치까지의 활동과 팀 사이 선후 관계를 시각화해 필요한 조정 범위를 찾는 활동이다.
- **지역 최적화(Local Optimization)**: 개별 팀의 완료량은 늘지만 통합 가치 전달시간이나 전체 성과는 개선되지 않는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 조직 규모만 보고 SAFe 역할•이벤트 일괄 도입 | 실제 **가치 흐름•의존성 지도화** 우선 | 불필요한 조정 계층 방지 |
| PI 계획이 근거 없는 장기 약속으로 변질 | 과거 용량•의존성과 변경 기준 명시 | 실행 가능한 공동 계획 수립 |
| 팀별 완료량과 달리 통합 가치 전달 지연 | 시스템 데모•**흐름 지표**와 **작업 진행 한도** 적용 | **지역 최적화** 방지 |
| 포트폴리오 통제로 팀 결정까지 중앙화 | 투자•위험 **가드레일** 내 실행 자율성 보장 | 전략 정렬•현장 속도 균형 |

#### 한줄 요약

- **가치 흐름•의존성 지도화**, **흐름 지표**, **가드레일**로 조정 범위를 최소화한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **팀 의존성**: 한 팀의 산출물이나 일정이 다른 팀 작업의 시작•완료를 제약하는 관계이다.
- **ART 적용**: 다수 팀의 목표와 의존성을 공통 조직으로 정렬하는 결정이다.
- **PI 적용**: 다수 팀의 개발 일정을 공통 주기로 정렬하는 결정이다.
- **SAFe 적용 기준**: 가치 흐름 범위와 팀 의존성을 비교해 ART와 PI의 적용 여부를 정하는 기준이다.

</details>

- 가치 흐름 범위와 **팀 의존성**이 크면 **ART 적용**과 **PI 적용**을 선택하는 것이 **SAFe 적용 기준**이다.

#### 한줄 요약

- 가치 흐름 범위와 팀 의존성을 함께 평가하는 것이 핵심이다.
