## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비동기 논블로킹 I/O(Async Non-blocking I/O)**: I/O 요청 시 스레드를 대기 상태로 멈추지 않고 즉시 반환하며, I/O 완료 시 이벤트를 통해 통지받는 I/O 모델.
- **이벤트 루프(Event Loop)**: 단일 스레드가 이벤트 큐(Event Queue)를 무한 루프로 순회하며 I/O 완료 이벤트를 처리하는 디스패치 엔진.

</details>

- 정의/개념: 논블로킹 소켓과 커널 I/O 다중화 통지(**epoll/kqueue/io_uring**)를 단일 스레드가 순환 디스패치하는 **리액터 패턴(Reactor Pattern)** 아키텍처
- 배경/필요성: 요청당 스레드를 1:1로 할당하는 동기 블로킹(Thread-per-Request) 모델이 유발하는 극심한 스택 메모리 낭비, 문맥 전환 오버헤드 및 C10K 동시 연결 한계를 극복하고, 단일(소수) 이벤트 루프 스레드와 커널 I/O 다중화 통지(epoll/kqueue/io_uring)를 결합한 리액터 패턴(Reactor Pattern)을 통해 **최소한의 자원 소비로 수만~수십만 개의 동시 I/O 연결을 초저지연 처리**할 필요

#### 한줄 요약
- 단일 스레드 이벤트 루프와 커널 epoll 다중화로 수만 개의 동시 I/O 연결을 초저지연 처리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **I/O 멀티플렉싱(I/O Multiplexing)**: 단일 스레드가 $O(1)$ 복잡도로 수만 개의 파일 디스크립터(소켓)의 읽기/쓰기 가능 상태를 동시에 감시하는 기술.
- **리액터 패턴(Reactor Pattern)**: 단일 디스패처(이벤트 루프)가 이벤트를 감지하여 등록된 서비스 핸들러로 전달하는 비동기 이벤트 주도 패턴.

</details>

- 소수의 스레드만으로 수만 개의 동시 접속 소켓을 처리하는 **C10K 문제 해결**
- **리액터 패턴** 기반으로 가벼운 네트워크 I/O는 즉시 처리하고, 무거운 연산은 워커 스레드 풀로 오프로드
- 이벤트 루프 스레드가 절대 블로킹되지 않도록 유지하는 것이 전체 처리량의 핵심

#### 한줄 요약
- 이벤트 루프는 문맥 전환 비용을 없애는 대신 어떤 작업도 루프를 오래 붙잡으면 안 된다는 제약을 코드 전체에 부과한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **io_uring**: 리눅스 최신 비동기 인터페이스로, 유저/커널 공간이 공유 링버퍼(Submission/Completion Queue)를 사용하여 시스템 콜 0회로 I/O를 수행.

</details>

```text
[비동기 I/O 및 이벤트 루프(Reactor) 아키텍처]
|-- 클라이언트 소켓 연결 요청 (수만 개 동시 인입)
|-- 커널 I/O 멀티플렉싱 계층 (epoll / kqueue / io_uring)
|   `-- I/O 준비 완료 이벤트를 이벤트 큐에 비동기 삽입
|-- 이벤트 루프 엔진 (단일 메인 스레드 무한 순환)
|   |-- Event Queue에서 완료 이벤트 추출 (Dequeue)
|   |-- 가벼운 비즈니스 콜백 즉시 실행
|   `-- 무거운 CPU 연산 및 파일 I/O -> 워커 스레드 풀 위임
`-- 워커 스레드 풀 (Worker Thread Pool - libuv 백그라운드 스레드)
```

선의 의미: 계층 및 이벤트 큐 기반 비동기 디스패치 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| 커널 멀티플렉서 | 준비된 소켓의 **이벤트 감지·전달** |
| 이벤트 큐 | 완료 콜백의 **FIFO 대기** |
| 이벤트 루프 | 이벤트 폴링과 **콜백 디스패치** |
| 워커 스레드 풀 | 무거운 작업의 **백그라운드 처리** |

#### 한줄 요약
- 커널 epoll이 준비 상태 통지를 대신해 주기 때문에 단일 루프가 다수 연결을 감당하며, 워커 스레드 풀은 루프가 절대 맡으면 안 되는 작업의 배출구 역할을 한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **이벤트 루프 블로킹(Event Loop Blocking)**: 이벤트 루프 스레드 안에서 동기 파일 읽기나 CPU 무한 루프가 실행되어 전체 서비스가 멈추는 치명적 장애.

</details>

```text
클라이언트 I/O 요청 인입 (Non-blocking 소켓 등록)
        │
   이벤트 루프가 epoll에 파일 디스크립터 등록 후 즉시 다음 작업으로 리턴
        │
   커널 레벨에서 네트워크 패킷 수신 완료
        │
   epoll이 준비 완료(Ready) 이벤트를 이벤트 큐에 삽입
        │
   이벤트 루프가 큐에서 이벤트를 꺼내 콜백 실행
   ┌────┴───────────────────────────┐
[가벼운 데이터 파싱/응답]         [무거운 CPU 연산/파일 I/O]
이벤트 루프에서 즉시 완료             워커 스레드 풀로 작업 위임 (Offload)
후 클라이언트에 패킷 전송            │
                                  워커 완료 후 완료 이벤트를 다시 이벤트 큐에 투입
```

#### 한줄 요약
- 콜백을 루프에서 직접 처리할지 워커로 위임할지가 갈림길이며, 연산 작업을 루프에 남기면 그 시간만큼 전체 연결의 지연이 함께 늘어난다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **동기 블로킹 vs 비동기 논블로킹**: 요청 후 응답까지 멈추는 전통적 서블릿(Tomcat)과 요청 즉시 리턴하고 이벤트로 처리하는 Netty/Node.js.

</details>

| 비교 항목 | 동기 블로킹 모델 (Thread-per-Request) | 비동기 이벤트 루프 (Reactor Pattern) |
|:---|:---|:---|
| 스레드 할당 | **연결(요청)당 1개 OS 스레드 독점** | **단일(소수) 이벤트 루프 스레드가 전담** |
| 메모리 소비 | 스레드 수 비례 (스레드당 1MB) | **극소량 (연결 수 증가에도 스레드 고정)** |
| C10K 동시성 | 메모리 고갈 및 문맥 전환 폭증 | **수만~수십만 동시 연결 거뜬히 수용** |
| 코드 스타일 | 명령형 동기 코드 (직관적, 디버깅 용이) | 비동기 콜백 / Promise / Reactive 체인 |
| 대표 솔루션 | 전통 Spring MVC, Apache HTTPD | Node.js, Netty, Nginx, Redis |

#### 한줄 요약
- 단순 저동시성은 동기 블로킹, 대규모 고동시성 I/O는 비동기 이벤트 루프가 최적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **백프레셔(Backpressure)**: 이벤트 수신 속도가 처리 속도를 초과할 때 상위 클라이언트의 전송 속도를 억제하여 큐 메모리 오버플로우를 막는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이벤트 루프 내 CPU 집약 연산으로 인한 **전체 루프 블로킹** | 무거운 작업을 **별도 워커 스레드 풀(`worker_threads`)** 로 분리 | 이벤트 루프의 마이크로초 단위 반응성 유지 |
| 콜백 지옥(Callback Hell)으로 인한 코드 가독성 저하 | **`async/await` 및 Promise 패턴** 표준화 | 동기식 코드 수준의 가독성 및 유지보수성 확보 |
| 트래픽 폭증 시 이벤트 큐 메모리 누적으로 OOM 발생 | 리액티브 스트림즈 **백프레셔(Backpressure) 및 소켓 읽기 일시 중지** | 큐 메모리 상한선 통제 및 시스템 가용성 보장 |
| 시스템 콜 오버헤드 극복 필요 | 최신 리눅스 커널 **io_uring 제로카피 비동기 I/O** 도입 | Syscall 비용 0화 및 파일 I/O 속도 2배 향상 |

#### 한줄 요약
- 이벤트 루프는 스레드 비용을 없애는 대신 단 하나의 블로킹 호출에 전체가 멈추는 위험을 지므로, 블로킹·연산 작업은 워커 풀로 내보내고 유입은 백프레셔로 눌러 루프를 비워 둔다.

## Ⅶ. 결론

- 현대 초고성능 네트워크 엔진(Netty, Nginx, Redis, Node.js) 및 실시간 API 서버의 **핵심 비동기 동시성 아키텍처**로 확립되었으며, 실무 설계에서는 **이벤트 루프의 무중단 반응성을 보장하기 위해 CPU 집약 연산/블로킹 파일 I/O의 워커 스레드 풀 오프로드, 큐 포화를 방지하는 리액티브 백프레셔(Backpressure), 시스템 콜 오버헤드를 극소화하는 Linux io_uring 인터페이스**를 결합하여 운영

#### 한줄 요약
- 비동기 I/O와 이벤트 루프는 스레드 생성 비용을 원천 제거하고 커널 멀티플렉싱을 통해 대규모 동시성을 실현하는 현대 웹/네트워크 인프라의 핵심이다.
