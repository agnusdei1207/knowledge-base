## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터베이스 무결성 제약조건(Database Integrity Constraint)**: 저장할 때 값의 범위와 행의 식별자 및 테이블 관계가 모두 유효하도록 강제하는 규칙이다.
- **데이터베이스(Database, DB)**: 구조화된 데이터를 통합 관리하는 저장 체계다.
- **고아 데이터(Orphan Data)**: 참조하는 부모 행이 존재하지 않아 관계가 끊어진 자식 데이터이다.

</details>

- 정의/개념: 저장 시 **값•식별•관계의 유효성을 강제하는 규칙**이다.
- 배경/필요성: 화면•응용 검증만으로는 우회 입력의 **잘못된 값•고아 데이터를 일관되게 차단하기 어려움**이 발생한다.

#### 한줄 요약

- 장부 자체에 규칙을 걸어 잘못된 값과 끊어진 관계가 기록되지 않게 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **선제 차단**: 잘못된 데이터가 저장되기 전에 변경 시점에 위반을 거부하는 특성이다.
- **중앙 통제**: 입력 애플리케이션과 관계없이 데이터베이스가 모든 변경 경로에 같은 규칙을 적용하는 방식이다.
- **선언적 관리**: 처리 절차를 직접 작성하지 않고 키•NULL•CHECK 같은 허용 조건으로 규칙을 명시하는 방식이다.

</details>

- **선제 차단**: 변경 시점에 위반 데이터 거부이다.
- **중앙 통제**: 모든 입력 경로에 같은 규칙을 적용한다.
- **선언적 관리**: 키•NULL•CHECK 조건 명시이다.

#### 한줄 요약

- DB가 모든 입력을 같은 규칙으로 검사하므로 안전하지만 검사 비용은 든다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **키 인덱스**: 기본키•유일키•외래키의 중복과 참조 대상을 빠르게 찾도록 지원하는 구조이다.
- **도메인 제약**: 열의 데이터 타입과 NULL 허용 여부 및 값 조건을 제한하는 규칙이다.
- **개체 제약**: 기본키와 유일키로 각 행을 중복 없이 식별하도록 하는 규칙이다.
- **참조 제약**: 외래키가 존재하는 부모 키만 가리키고 삭제•갱신 동작을 따르도록 하는 규칙이다.
- **기본키(Primary Key, PK)**: 행을 대표해 유일하게 식별하는 키다.
- **유일 제약(Unique Constraint, UNIQUE)**: 후보키 값의 중복을 막는 제약이다.
- **외래키(Foreign Key, FK)**: 부모 행의 후보키를 참조하는 키다.
- **구조화 질의 언어(Structured Query Language, SQL)**: 관계형 데이터의 정의•조작•제어 언어다.

</details>

```text
                 [도메인 제약]
                       |
                 [SQL 처리기]
                  /         \
          [개체 제약]     [참조 제약]
                  \         /
                  [키 인덱스]
```

선의 의미: SQL 처리기는 도메인·개체·참조 제약을 적용하고, 키 인덱스는 개체 제약의 유일성 검사와 참조 제약의 부모 키 탐색을 지원한다.

| 구성요소 | 책임 |
|:---|:---|
| SQL 처리기 | **변경문 해석•실행 계획** 수립 |
| 도메인 제약 | **타입•NOT NULL•CHECK** 검사 |
| 개체 제약 | **PK•UNIQUE 식별•중복** 검사 |
| 참조 제약 | **FK 부모 존재•참조 동작** 검사 |
| 키 인덱스 | **유일성•참조 키 탐색** 지원 |

#### 한줄 요약

- 값•행•관계 규칙과 키 탐색 장치가 잘못된 저장을 차단한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **도메인 제약 검증**: 타입•NULL•CHECK 규칙을 확인하는 단계다.
- **개체 제약 검증**: 기본키•유일키의 중복을 확인하는 단계다.
- **참조 제약 검증**: 외래키의 부모 존재와 참조 동작을 확인하는 단계다.
- **변경•참조 동작 적용**: 검증된 변경과 삭제•갱신 정책을 실행하는 단계다.

</details>

```text
삽입•수정•삭제 후보
          |
          v
1. 도메인 제약 검증
          |
          +-- 위반 --> 제약 위반 반환
          |
          v
2. 개체 제약 검증
          |
          +-- 중복 --> 제약 위반 반환
          |
          v
3. 참조 제약 검증
          |
          +-- 관계 위반 --> 제약 위반 반환
          |
          v
4. 변경•참조 동작 적용
          |
          v
커밋 결과 반환
```

**동작 원리**

- **1. 도메인 제약 검증**: 타입•NULL•CHECK 규칙을 확인한다.
- **2. 개체 제약 검증**: 기본키•유일키 중복을 판정한다.
- **3. 참조 제약 검증**: 부모 키 존재와 참조 동작을 확인한다.
- **4. 변경•참조 동작 적용**: 검증된 상태만 저장한다.

#### 한줄 요약

- 값의 범위, 행의 이름표, 부모와의 연결을 차례로 확인한 뒤 저장한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **도메인 무결성**: 속성값이 정해진 형식과 범위를 벗어나지 않도록 보장하는 무결성이다.
- **개체 무결성**: 기본키가 NULL이나 중복 없이 각 행을 유일하게 식별하도록 보장하는 무결성이다.
- **참조 무결성**: 외래키가 NULL이거나 실제 존재하는 후보키를 가리키도록 보장하는 무결성이다.

</details>

| 무결성 유형 | 도메인 무결성 | 개체 무결성 | 참조 무결성 |
|:---|:---|:---|:---|
| 적용 기준 | **값의 형식•범위** | **행의 유일 식별** | **부모•자식 관계** |
| 핵심 특징 | **타입•NOT NULL•CHECK** | **PRIMARY KEY•UNIQUE** | **FOREIGN KEY** |
| 한계 | **복합 업무 규칙** 표현 제한 | **키 변경의 연쇄 영향** | **삭제 정책의 대량 영향** |

> 요약: **외래키**는 유일성을 보장하는 **후보키** 도 참조 가능이 핵심이다.

#### 한줄 요약

- 도메인은 값, 개체는 행의 이름표, 참조는 테이블 사이의 연결을 지킨다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **데이터베이스 불변식(Database Invariant)**: 모든 저장 경로가 지켜야 하는 규칙이다.
- **사용자 인터페이스 검증(User Interface Validation, UI Validation)**: 입력 오류를 즉시 알리는 화면 검증한다.
- **삭제 정책(Delete Policy)**: 부모 삭제 시 자식 행 처리 방식을 정한 규칙이다.
- **갱신 정책(Update Policy)**: 부모 키 갱신 시 자식 행 처리 방식을 정한 규칙이다.
- **사전 진단(Pre-assessment)**: 제약 활성화 전에 기존 위반 데이터를 찾는 활동이다.
- **데이터 정제(Data Cleansing)**: 발견한 제약 위반 데이터를 고치는 활동이다.
- **단계 활성화(Phased Enforcement)**: 새 제약을 점진적으로 검증하고 강제하는 절차다.
- **참조 키 인덱스(Foreign-key Index)**: 외래키 대상 탐색을 돕는 인덱스다.
- **유일 키 인덱스(Unique-key Index)**: 유일성 검사를 돕는 인덱스다.
- **확장-축소 변경(Expand-Contract Change)**: 구버전과 호환되는 구조를 먼저 추가한 뒤 전환이 끝나면 옛 구조를 제거하는 스키마 변경 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DB 불변식과 화면 편의 검증을 섞어 규칙 중복•불일치 | **DB 불변식•화면 검증 역할** 분리 | **규칙 중복•불일치** 감소 |
| 부모 삭제 동작을 정하지 않아 대량 연쇄 삭제 | **관계별 삭제•갱신 정책** 명시 | **의도치 않은 연쇄 삭제** 방지 |
| 위반 데이터가 남은 상태에서 새 제약 활성화 실패 | **사전 진단•정제•단계 활성화** | **제약 추가 실패** 방지 |
| 참조•유일 키 탐색이 느려 쓰기 검사 지연 | **참조•유일 키 인덱스** 점검 | **쓰기 검사 지연** 감소 |
| 구버전 실행 중 제약을 즉시 강화해 배포 충돌 | **확장-축소 변경** 적용 | **구버전•스키마 충돌** 방지 |

> 적용 사례: 고객 ID 외래키와 삭제 제한으로 고아 주문 데이터 차단

#### 한줄 요약

- 규칙을 DB에 선언하되 기존 데이터, 삭제 영향, 검사 비용을 함께 확인해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **값 규칙(Value Rule)**: 열에 저장할 수 있는 값의 조건이다.
- **키 규칙(Key Rule)**: 행 식별과 중복을 통제하는 조건이다.
- **관계 규칙(Relationship Rule)**: 부모와 자식 행의 참조 조건이다.
- **변경 영향(Change Impact)**: 제약 추가가 기존 데이터와 응용에 미치는 범위다.

</details>

- 모든 저장 경로의 **불변식**은 DB에, **화면 검증**은 응용에 배치한다.

#### 한줄 요약

- 데이터 규칙을 장부 자체가 지키게 하면 어떤 입력 경로에서도 같은 기준을 적용할 수 있다.
