## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터베이스 샤딩(Database Sharding)**: 단일 DB의 수직 확장(Scale-Up) 한계를 극복하기 위해 대용량 데이터를 샤드 키 기준으로 분할하여 여러 독립된 물리 DB 노드에 수평 분산(Scale-Out) 저장하는 아키텍처.
- **수직 확장 한계 및 트랜잭션 병목(Scale-Up Limit & Bottleneck)**: 단일 서버의 CPU, 메모리, I/O 대역폭 포화로 인해 동시 트랜잭션 처리량이 급락하는 현상.

</details>

- 정의/개념: 단일 데이터베이스의 용량 및 처리량 한계를 극복하기 위해 **샤드 키(Shard Key)를 기준으로 데이터를 복수의 물리 DB 노드에 수평 분산**하는 분할 아키텍처
- 배경/필요성: 단일 DB 인스턴스의 하드웨어 수직 확장(Scale-Up) 한계 직면 및 **스토리지 용량 고갈과 대규모 동시 트랜잭션 병목 위험** 직면

#### 한줄 요약

- 샤드 키를 기반으로 데이터를 독립된 물리 노드들에 수평 분산하여 무제한에 가까운 확장성을 확보

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Shared-Nothing 아키텍처**: 각 샤드 노드가 CPU, 메모리, 디스크를 독립적으로 소유하고 네트워크를 통해서만 통신하는 완전 분산 구조.
- **일관된 해싱(Consistent Hashing)**: 노드 증설이나 삭제 시 전체 데이터의 재배치 없이 $1/N$의 데이터만 최소 이동시키는 분산 해싱 알고리즘.

</details>

- 독립된 물리 서버를 지속 추가하여 용량을 증설하는 **Shared-Nothing 기반 수평 확장(Scale-Out)**
- 데이터 편향(Data Skew)을 방지하고 균등 배치를 유도하는 **샤드 키(Shard Key) 설계**
- 샤드 노드 증감 시 리밸런싱 비용을 최소화하는 **일관된 해싱(Consistent Hashing) 적용**

#### 한줄 요약

- Shared-Nothing 수평 확장과 일관된 해싱을 통해 대규모 읽기/쓰기 처리량을 선형적으로 확장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **샤드 라우터(Shard Router)**: 애플리케이션의 쿼리를 분석하여 샤드 키에 해당하는 물리 DB 노드로 쿼리를 전달하는 라우팅 미들웨어.

</details>

```text
[ 데이터베이스 샤딩 아키텍처 구조도 ]

                       [ 클라이언트 애플리케이션 ]
                                    │
                                    ▼
                       [ 샤드 라우터 / 미들웨어 ]
                                    │ (샤드 키 라우팅)
                 ┌──────────────────┼──────────────────┐
                 ▼                  ▼                  ▼
          [ 샤드 노드 1 ]     [ 샤드 노드 2 ]     [ 샤드 노드 3 ]
          (user_id 1~1000)   (user_id 1001~2000) (user_id 2001~3000)
```

선의 의미: 샤드 라우터가 샤드 키 규칙에 따라 쿼리를 대상 물리 DB 노드로 분기 전달하는 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 샤드 라우터 (Router) | 샤드 키를 파싱하여 **해당 쿼리를 적절한 물리 DB 노드로 라우팅** |
| 샤드 노드 집합 | 분할된 데이터 조각을 독립적으로 저장하고 **로컬 트랜잭션 및 인덱스 처리** |
| 메타데이터 카탈로그 | 샤드 노드 매핑 정보 및 **해시 링(Hash Ring) 범위 구성 관리** |
| 재분배 관리자 | 노드 추가/제거 시 **데이터 마이그레이션 및 리밸런싱 자동 통제** |

#### 한줄 요약

- 샤드 라우터, 샤드 노드, 메타데이터 카탈로그, 재분배 관리자가 결합하여 수평 분산을 실현

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **샤드 쿼리 라우팅 파이프라인**: 쿼리 접수 $\to$ 샤드 키 추출 $\to$ 해시 링 매핑 $\to$ 타깃 샤드 노드 실행 $\to$ 결과 취합.

</details>

```text
[ 샤드 쿼리 라우팅 5단계 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 쿼리 접수: SQL 파싱 및 샤드 키 추출│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 메타데이터 조회: 해시 링/범위 매핑  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 대상 노드 결정: 타깃 샤드 인스턴스  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 로컬 쿼리 실행: 단일 노드 내 처리  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 결과 반환 및 모니터링 메트릭 기록   │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 쿼리 접수: 클라이언트의 SQL에서 WHERE 절의 샤드 키(예: `user_id`)를 파싱하여 추출.
2. 메타데이터 조회: 일관된 해시 링 또는 범위 테이블을 참조하여 해당 키가 속한 샤드 노드 ID를 확인.
3. 대상 노드 결정: 타깃 물리 DB 커넥션을 획득하고 쿼리를 원격 노드로 전달.
4. 로컬 쿼리 실행: 샤드 노드 내부에서 로컬 인덱스를 활용하여 읽기/쓰기를 즉시 실행.
5. 결과 반환: 단일 노드 결과를 클라이언트에 즉시 반환하고 노드별 부하율을 기록.

#### 한줄 요약

- 키 추출 $\to$ 메타데이터 매핑 $\to$ 대상 노드 결정 $\to$ 로컬 실행 $\to$ 결과 반환의 5단계 파이프라인

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **파티셔닝 vs 샤딩**: 단일 DB 서버 내에서 테이블/파일을 분할하는 파티셔닝과 다중 물리 서버로 분산하는 샤딩.

</details>

| 구분 | 테이블 파티셔닝 (Partitioning) | 데이터베이스 샤딩 (Sharding) |
|:---|:---|:---|
| **적용 기준** | 단일 서버 스펙 내 대용량 테이블 관리 최적화 | 단일 서버 하드웨어 한계를 초과하는 초대규모 트래픽 |
| **핵심 특징** | **단일 OS/DBMS 엔진 내 파일 레벨 분할 (Shared-Disk)** | **다중 독립 DB 노드 간 네트워크 수평 분산 (Shared-Nothing)** |
| **한계** | 단일 인스턴스 CPU 및 메모리 물리적 한계 봉착 | 교차 샤드 조인 및 분산 트랜잭션 관리 복잡도 증가 |

#### 한줄 요약

- 단일 인스턴스 관리는 파티셔닝, 물리적 한계를 초과하는 대규모 확장은 샤딩을 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **교차 샤드 조인(Cross-Shard Join)**: 여러 샤드 노드에 분산된 테이블 간의 조인으로 인해 네트워크 I/O 및 분산 취합(Scatter-Gather) 비용이 급증하는 문제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 교차 샤드 조인(Cross-Shard Join)으로 인한 네트워크 병목 | **동일 샤드 키 기준 테이블 코로케이션(Co-location) 및 비정규화** | 단일 노드 로컬 조인으로 전환 |
| 다중 샤드에 걸친 분산 트랜잭션(2PC) 성능 저하 | **Saga Pattern 기반 보상 트랜잭션 및 비동기 이벤트 일관성 적용** | 2PC 락 블로킹 해소 및 고가용성 확보 |
| 노드별 시퀀스 충돌로 인한 고유 ID 생성 난해 | **Twitter Snowflake, UUID v7, TSID 기반 분산 ID 생성기 도입** | 전역 유일 정렬 ID 보장 |

#### 한줄 요약

- 테이블 코로케이션, Saga 분산 트랜잭션, 분산 ID 생성기를 통해 샤딩의 구조적 난제를 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **샤딩 미들웨어(Sharding Middleware)**: Vitess, Apache ShardingSphere 등 애플리케이션 변경 없이 샤딩 라우팅과 분산 쿼리를 투명하게 처리해 주는 프레임워크.

</details>

- **데이터베이스 샤딩** 페타바이트급 대규모 분산 환경에서 시스템 생존을 보장하는 궁극의 확장 전략이며, 비즈니스 도메인에 부합하는 샤드 키 선정과 분산 아키텍처 패턴을 철저히 결합해야 함

#### 한줄 요약

- 최적의 샤드 키 설계와 Shared-Nothing 수평 확장을 통해 대용량 분산 데이터베이스를 완성
