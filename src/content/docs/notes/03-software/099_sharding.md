## 미리 알고가기

- **샤딩 (Sharding)**: 논리 데이터를 여러 노드에 수평 분산함
- **샤드 키 (Shard Key)**: 데이터의 대상 샤드를 결정함
- **샤드 라우터 (Shard Router)**: 요청을 대상 샤드로 전달함
- **재샤딩 (Resharding)**: 샤드 범위와 데이터 배치를 다시 조정함
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **식별자 (Identifier, ID)**: 대상을 유일하게 구분하는 값임
- **노드(Node)**: 분산 시스템에서 데이터 저장이나 요청 처리를 맡는 독립 실행 단위임
- **수평 확장(Scale-out)**: 서버의 성능을 키우는 대신 노드 수를 늘려 용량과 처리량을 높이는 방식임
- **교차 샤드 질의(Cross-shard Query)**: 둘 이상의 샤드에서 데이터를 읽어 결과를 합치는 질의임
- **분산 트랜잭션(Distributed Transaction)**: 여러 노드의 변경을 하나의 논리 작업으로 조정하는 트랜잭션임
- **팬아웃(Fan-out)**: 하나의 요청을 여러 샤드에 동시에 보내고 결과를 모으는 처리임
- **재균형(Rebalancing)**: 샤드 간 데이터와 요청의 편차를 줄이도록 배치를 옮기는 작업임

## Ⅰ. 개요

- **정의/개념**: 데이터를 여러 노드에 수평 분산함
- **배경/필요성**: 단일 노드 용량·처리량 한계로 샤딩 필요

### 쉽게 이해하기 (학습용)
- 한 도서관의 책을 여러 지점에 나누고 책 번호로 어느 지점에 있는지 찾는 방식임

## Ⅱ. 특징

- 노드 추가로 저장 용량과 처리량을 수평 확장한다.
- 샤드별 장애 격리는 전체 장애 확산을 줄인다.
- 교차 샤드 질의는 결과·커밋 조정 비용을 늘린다.
- 잘못된 샤드 키는 특정 노드에 과부하를 집중시킨다.

### 쉽게 이해하기 (학습용)
- 저장 공간은 늘지만 검색과 재배치 및 분산 트랜잭션이 복잡해짐

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 샤드 키 | 데이터 분포와 조회 경로를 결정함 |
| 라우팅 계층 | 요청을 대상 샤드로 전달함 |
| 배치 정보 | 샤드와 물리 노드의 위치를 연결함 |
| 재균형 절차 | 편중 시 데이터를 다시 배치함 |

```text
  응용요청
      ↓
  샤드키배치
      ↓
  요청라우팅
      ↓
  노드분산
```

> 요약: 샤드 키와 배치 정보로 요청과 데이터를 분산함

### 쉽게 이해하기 (학습용)
- 샤드 키와 배치 정보로 요청을 담당 노드에 전달함

## Ⅳ. 원리 및 절차 흐름도

```text
  키값추출
      ↓
  대상매핑
      ↓
  요청전달
      ↓
  결과병합
```

| 절차 | 설명 |
|:---|:---|
| 샤드키추출 | 요청에서 샤드 키를 추출함 |
| 샤드매핑 | 범위와 해시로 대상 노드를 매핑함 |
| 요청라우팅 | 대상 노드에 요청을 전달함 |
| 결과관리 | 단일 반환이나 다중 결과 병합을 수행함 |

> 요약: 샤드 키로 요청을 전달하고 다중 결과를 병합함

### 쉽게 이해하기 (학습용)
- 샤드 키로 노드를 찾고 다중 결과는 다시 병합함

## Ⅴ. 종류 및 비교

| 비교축 | 범위 샤딩 | 해시 샤딩 | 디렉터리 샤딩 |
|:---|:---|:---|:---|
| 핵심 특징 | 키 값 구간별로 샤드를 나눔 | 해시 결과로 샤드를 결정함 | 매핑 정보로 샤드를 찾음 |
| 적용 기준 | 구간 조회가 집중될 때 적용함 | 부하를 균등 분산할 때 적용함 | 가변 배치가 잦을 때 적용함 |
| 주요 위험 | 특정 구간 편중이 발생함 | 범위 조회가 확산됨 | 매핑 관리 계층이 추가됨 |

> 요약: 범위는 구간을 쓰고 해시는 분산하며 디렉터리는 매핑을 씀

### 쉽게 이해하기 (학습용)
- 구간은 범위를 쓰고 균등 분산은 해시를 쓰며 가변 배치는 디렉터리를 씀

## Ⅵ. 실무 사례

1. 사용자 시스템은 해시 샤딩을 적용하고 데이터 크기 편차를 확인함
2. 주문 검색은 별도 모델을 구성하고 팬아웃 지연을 확인함

### 쉽게 이해하기 (학습용)
- 사용자 식별자를 해시로 분산한 뒤 샤드별 데이터 크기와 요청량을 비교해야 실제 편중을 확인할 수 있음
- 주문 검색을 별도 조회 모델로 제공하면 모든 거래 샤드에 요청하는 팬아웃 지연을 줄일 수 있음

## Ⅶ. 결론

- 분포·조회 패턴에 맞는 키·라우팅·재균형 설계

### 쉽게 이해하기 (학습용)
- 샤딩은 편중률·교차 질의량·재배치 시간을 제한할 샤드 키와 운영 절차를 설계하는 일임
