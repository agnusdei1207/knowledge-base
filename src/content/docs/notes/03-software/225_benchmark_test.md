## 미리 알고가기

- **벤치마크 테스트 BMT(비엠티, Benchmark Test)**: 영어 핵심어의 첫 글자를 쓴 표기로 후보 제품을 같은 조건에서 실행해 기능·성능을 수치 비교하는 시험이다.
- **개념 검증 PoC(피오씨, Proof of Concept)**: 영어 세 낱말의 첫 글자를 쓴 표기로 새로운 기술이나 설계의 실제 구현 가능성을 제한된 범위에서 확인한다.
- **시험 시나리오**: 업무 흐름, 입력 자료, 부하, 실행 시간과 판정 기준을 한 묶음으로 정의한 시험 명세다.
- **작업 부하(Workload)**: 시험 대상에 발생시키는 요청 종류, 요청량, 동시 사용자와 자료 분포의 조합이다.
- **예열(Warm-Up)**: 연결과 임시 저장 상태를 안정시켜 초기 실행 편차를 측정에서 제외하는 준비 실행이다.
- **반복성(Repeatability)**: 같은 시험자와 환경에서 반복 측정했을 때 유사한 결과를 얻는 성질이다.
- **재현성(Reproducibility)**: 시험자나 환경이 달라도 명세대로 실행하면 허용 범위 안의 결과를 얻는 성질이다.
- **원시 측정 자료**: 평균값으로 가공하기 전의 요청별 시간, 오류, 자원 사용량과 실행 기록이다.

## Ⅰ. 개요

- **정의/개념**: 동일 조건의 **후보 제품 기능·성능 실증 비교**
- **배경/필요성**: 제안 사양의 **실제 처리 능력 검증 한계** 해소

### 쉽게 이해하기 (학습용)

- 여러 제품에 같은 장비와 같은 일을 주고 실제 속도와 오류를 재어 광고가 아닌 실행 결과로 비교한다.

## Ⅱ. 특징

- 공통 환경·부하의 **비교 조건 통제**
- 반복 측정의 **우연 편차 분리**
- 운영 대표 부하의 **결과 타당성 확보**

### 쉽게 이해하기 (학습용)

- 제품만 다르고 나머지 조건은 같아야 하며 실제 업무와 닮은 일을 여러 번 실행해야 믿을 수 있는 차이를 얻는다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart TB
    A["평가 기준"] -->|판정 지표| B["시험 시나리오"]
    B -->|공통 부하| C["실행 제어기"]
    D["동결 환경"] -->|동일 자원·설정| C
    C -->|후보별 실행| E["측정 증거"]
    E -->|점수·편차| A
```

| 설계 요소 | 설명 |
|:---|:---|
| 평가 기준 | 기능·성능 지표와 합격선을 정의 |
| 시험 시나리오 | 업무 자료·부하·실행 시간을 명시 |
| 실행 제어기 | 예열·반복·후보별 실행 순서 통제 |
| 동결 환경 | 장비·버전·조정 허용 범위를 고정 |
| 측정 증거 | 원시 자료·설정·실행 이력을 보존 |

> 요약: 동결 환경에서 공통 부하와 증거로 비교

### 쉽게 이해하기 (학습용)

- 같은 시험 문제와 장비를 준비하고 실행 순서까지 통제한 뒤 원래 측정 자료를 남겨 제품별 결과를 비교한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant 평가자
    participant 제어기
    participant 후보제품
    participant 측정기
    평가자->>제어기: 시험 조건 합의
    평가자->>제어기: 환경·설정 동결
    제어기->>후보제품: 예열 실행
    제어기->>후보제품: 공통 부하 실행
    후보제품->>측정기: 원시 자료 수집
    측정기->>평가자: 반복 결과 비교
```

| 절차 | 설명 |
|:---|:---|
| 시험 조건 합의 | 지표·부하·허용 조정 범위 확정 |
| 환경·설정 동결 | 후보별 장비와 설정 차이를 제거 |
| 예열 실행 | 초기 연결·임시 저장 편차를 제외 |
| 공통 부하 실행 | 같은 자료와 요청량을 반복 적용 |
| 원시 자료 수집 | 시간·오류·자원 사용량을 기록 |
| 반복 결과 비교 | 편차를 확인하고 기준대로 점수화 |

> 요약: 조건 동결 후 공통 부하를 반복 측정

### 쉽게 이해하기 (학습용)

- 시험 규칙과 설정을 먼저 잠그고 각 제품을 예열한 뒤 같은 일을 반복시켜 원래 측정값과 편차를 비교한다.

## Ⅴ. 종류 및 비교

| 기술 평가 방식 | 벤치마크 테스트 | 개념 검증 | 문서 평가 |
|:---|:---|:---|:---|
| 적용 기준 | 제품 간 수치 차이 확인 필요 | 신기술 구현 여부가 불확실 | 실행 시험 전 후보 선별 필요 |
| 핵심 특징 | 동일 조건의 후보 성능 비교 | 제한 구현의 실현 가능성 확인 | 제안 내용·실적의 수행성 판단 |
| 한계 | 비대표 부하·설정 편향 | 시범 성공의 운영성 오판 | 과장 제안·평가자 주관 편차 |

> 요약: 성능 비교·실현성·수행성에 맞춰 선택

### 쉽게 이해하기 (학습용)

- 제품의 실제 수치는 벤치마크, 새 기술의 구현 가능성은 개념 검증, 제안자의 계획과 경험은 문서 평가로 확인한다.

## Ⅵ. 실무 사례

1. DB 후보에 **동일 거래 부하 적용**
2. 저장장치 후보에 **동일 파일 입출력 적용**

### 쉽게 이해하기 (학습용)

- 데이터베이스마다 같은 거래 자료와 동시 요청을 반복해 처리 시간과 오류를 비교한다.
- 저장장치마다 같은 크기와 순서의 파일을 읽고 쓰게 해 처리량 차이를 비교한다.

## Ⅶ. 결론

- **운영 부하·동결 조건·원시 증거**로 후보 비교

### 쉽게 이해하기 (학습용)

- 벤치마크 결과는 최고 점수보다 실제 업무를 닮은 부하와 후보마다 동일한 조건을 입증할 자료가 있을 때 의미가 있다.
