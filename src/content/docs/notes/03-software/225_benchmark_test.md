## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **벤치마크 테스트(Benchmark Test, BMT)**: 후보 제품을 동일한 환경•자료•부하•측정 절차에서 실행해 기능 적합성과 성능을 수치로 비교하는 시험이다.
- **후보 제품(Candidate Product)**: 공통 시험 조건에서 기능과 성능을 비교할 평가 대상 제품이다.

</details>

- 정의/개념: 동일 환경•자료•부하•측정 절차에서 **후보 제품(Candidate Product)**을 비교하는 **벤치마크 테스트(Benchmark Test, BMT)**이다.
- 배경/필요성: 제안서만으로는 실제 처리 능력을 검증할 수 없다.

#### 한줄 요약

- 여러 제품에 같은 장비와 같은 일을 주고 실제 속도와 오류를 재어 광고가 아닌 실행 결과로 비교한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **반복 측정(Repeated Measurement)**: 같은 조건의 여러 실행 결과와 분산을 비교해 우연한 편차와 실제 제품 차이를 구분하는 방식이다.
- **조건 통제(Controlled Condition)**: 제품 외의 장비•자료•부하•설정•실행 절차를 후보마다 동일하게 유지하는 원칙이다.
- **대표 부하(Representative Workload)**: 운영 로그와 업무 비율을 반영해 실제 사용 특성을 재현한 시험 부하이다.

</details>

- **조건 통제(Controlled Condition)**로 후보 외 공통 환경•부하를 고정한다.
- **반복 측정(Repeated Measurement)**으로 우연 편차를 분리한다.
- **대표 부하(Representative Workload)**로 결과 타당성을 확보한다.

#### 한줄 요약

- 제품만 다르고 나머지 조건은 같아야 하며 실제 업무와 닮은 일을 여러 번 실행해야 믿을 수 있는 차이를 얻는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **실행 제어기(Execution Controller)**: 후보별 예열•반복 횟수•실행 순서와 공통 부하 적용을 통제하는 구성요소이다.
- **동결 환경(Frozen Environment)**: 시험 중 임의 변경하지 않도록 장비•소프트웨어 버전•튜닝 허용 범위를 확정한 환경이다.
- **측정 증거(Measurement Evidence)**: 결과 재현과 판정 추적에 필요한 원시 자료•설정•실행 이력이다.
- **평가 기준(Evaluation Criteria)**: 기능•성능 지표와 합격선을 사전에 정한 판정 기준이다.
- **시험 시나리오(Test Scenario)**: 업무 자료•부하•실행 시간과 순서를 명시한 시험 절차이다.

</details>

```text
평가 기준
├── 시험 시나리오
├── 동결 환경
└── 실행 제어기
    └── 측정 증거
```

선의 의미: 평가 기준과 시험 시나리오 및 동결 환경이 실행 제어기의 공통 시험 경계를 규정하고, 측정 증거가 그 환경과 실행 조건의 재현 근거를 보존하는 정적 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| **평가 기준(Evaluation Criteria)** | 기능•성능 지표와 합격선 정의 |
| **시험 시나리오(Test Scenario)** | 업무 자료•부하•실행 시간 명시 |
| **동결 환경(Frozen Environment)** | 장비•버전•조정 범위 고정 |
| **실행 제어기(Execution Controller)** | 예열•반복•실행 순서 통제 |
| **측정 증거(Measurement Evidence)** | 원시 자료•설정•이력 보존 |

#### 한줄 요약

- 같은 시험 문제와 장비를 준비하고 실행 순서까지 통제한 뒤 원래 측정 자료를 남겨 제품별 결과를 비교한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **4. 원시 자료 저장**: 각 후보의 요청별 시간•오류•자원 사용량과 실행 설정을 가공 전 상태로 보존하는 단계이다.
- **1. 시험 조건 확정**: 지표•대표 부하•반복 횟수•합격선을 사전에 등록하는 단계이다.
- **2. 환경•설정 동결**: 후보별 장비•버전과 튜닝 허용 범위를 고정하는 단계이다.
- **3. 공통 부하 실행**: 예열 후 같은 업무 요청을 정한 순서와 횟수로 실행하는 단계이다.
- **5. 반복 결과 판정**: 측정값의 편차와 분산을 확인한 뒤 기준별 점수를 확정하는 단계이다.

</details>

```text
1. 시험 조건 확정
        |
        v
2. 환경•설정 동결
        |
        v
3. 공통 부하 실행
        |
        v
4. 원시 자료 저장
        |
        +-- 반복 횟수 미달 ---- 공통 부하 재실행
        |
        `-- 반복 횟수 충족
                  |
                  v
         5. 반복 결과 판정
                  |
                  `-- 기준별 점수•합격 여부
```

### 동작 원리

1. **시험 조건 확정**: 지표•부하•합격선을 등록한다.
2. **환경•설정 동결**: 장비•버전•조정 범위를 고정한다.
3. **공통 부하 실행**: 예열 후 동일 요청을 반복한다.
4. **원시 자료 저장**: 시간•오류•사용량을 기록한다.
5. **반복 결과 판정**: 편차 확인 후 기준별로 채점한다.

#### 한줄 요약

- 시험 규칙과 설정을 먼저 잠그고 각 제품을 예열한 뒤 같은 일을 반복시켜 원래 측정값과 편차를 비교한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **개념 증명(Proof of Concept, PoC)**: 신기술이나 설계 방안의 구현 가능성을 제한된 범위에서 검증하는 시험이다.
- **문서 평가(Document Evaluation)**: 제안 내용•실적•수행 계획을 증거 자료로 검토해 시험 전 후보를 선별하는 방식이다.

</details>

| 기술 평가 방식 | **벤치마크 테스트(Benchmark Test, BMT)** | **개념 증명(Proof of Concept, PoC)** | **문서 평가(Document Evaluation)** |
|:---|:---|:---|:---|
| 적용 기준 | 제품 간 수치 차이 확인 | 신기술의 구현 여부 불확실 | 실행 시험 전 후보 선별 |
| 핵심 특징 | 동일 조건의 후보 성능 비교 | 제한 구현의 실현 가능성 확인 | 제안 내용•실적의 수행성 판단 |
| 한계 | 비대표 부하•설정 편향 | 시범 성공의 운영성 오판 | 과장 제안•평가자 주관 편차 |

> 요약: 성능 비교•실현성•수행성에 맞춰 평가 방식을 선택한다.

#### 한줄 요약

- 제품의 실제 수치는 벤치마크, 새 기술의 구현 가능성은 개념 검증, 제안자의 계획과 경험은 문서 평가로 확인한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **설정 편차**: 후보별 튜닝 범위가 달라 제품 자체가 아닌 시험 조건 차이가 결과를 만드는 문제이다.
- **예열(Warm-Up)**: 초기 적재•컴파일•캐시 효과가 안정된 뒤 본 측정을 시작하도록 미리 부하를 실행하는 절차이다.
- **분산(Variance)**: 반복 측정값이 평균 주변에 얼마나 퍼져 있는지 나타내는 통계량이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비대표 작업 부하 | 운영 로그로 **대표 부하(Representative Workload)** 구성 | 결과 대표성 확보 |
| 후보별 **설정 편차** | 조정 허용 범위 사전 동결 | 비교 공정성 확보 |
| 단일 실행의 우연 편차 | **예열(Warm-Up)** 후 반복값•**분산(Variance)** 공개 | 결과 재현성 향상 |
| 요약 점수만 보존 | **측정 증거(Measurement Evidence)** 보관 | 판정 추적성 확보 |

#### 한줄 요약

- 데이터베이스마다 같은 거래 자료와 동시 요청을 반복해 처리 시간과 오류를 비교한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **후보 선정 기준**: 운영 대표 부하의 반복 측정 결과가 사전 합격선을 충족한 제품만 선정하는 기준이다.
- **사전 합격선(Predefined Acceptance Threshold)**: 결과를 보기 전에 정한 기능•성능•오류율의 최소 통과 기준이다.

</details>

- **후보 선정 기준**에 따라 **사전 합격선(Predefined Acceptance Threshold)**을 충족한 제품만 선정한다.

#### 한줄 요약

- 최고 점수보다 실제 업무와 같은 부하와 후보별 동일 조건을 입증할 자료가 중요하다.
