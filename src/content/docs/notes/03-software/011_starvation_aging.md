## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Starvation (기아 현상)**: 우선순위 기반 스케줄링 환경에서 높은 우선순위를 갖는 신규 프로세스들이 지속 유입됨으로 인해, 하위 우선순위 프로세스가 CPU 자원을 영구히 할당받지 못하고 블록되는 부작용.
- **Aging (에이징 기법)**: Ready Queue 내에서 대기하는 시간에 비례하여 프로세스의 우선순위 수치(Priority Score)를 점진적으로 상승시켜 기아 현상을 차단하는 기법.

</details>

- 정의/개념: 우선순위 스케줄링 시 저우선순위 프로세스의 무한 대기 현상인 **Starvation(기아)** 및 대기시간 경과에 비례하여 우선순위를 동적 격상시키는 **Aging(에이징)**
- 배경/필요성: 고우선순위 작업의 지속 유입은 **저우선순위 실행 기회 박탈**

#### 한줄 요약

- 누적 대기시간에 따라 우선순위를 높여 기아를 방지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Priority Ceiling (우선순위 상한)**: 에이징 승격 시 저우선순위 프로세스가 하드 실시간/시스템 커널 프로세스의 최고 우선순위 영역을 침범하지 않도록 제한하는 상한선.
- **Aging Step (상향 폭)**: 단위 시간 $T$ 경과 시마다 우선순위 수치를 얼마만큼 가산 인가할지 결정하는 튜닝 파라미터.

</details>

- 자원 독점에 따른 저우선순위 프로세스의 영구 무한 대기(**Starvation**) 파급
- 대기시간 누적 메트릭 기반 동적 우선순위 격상(**Aging**)
- **Aging Step** 및 **Priority Ceiling** 조절을 통한 실시간 긴급 태스크 보존 및 공정성 확보

#### 한줄 요약

- 상향 주기•폭•상한으로 대기 보장과 긴급성을 절충한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Wait-Time Counter**: PCB/TCB 내에서 프로세스가 Ready Queue에 수용된 이후 지나간 시간을 누적 계측하는 카운터.

</details>

```text
[대기시간 계수기] -- [에이징 정책] -- [우선순위 준비 큐]
                                              |
                                         [스케줄러]
```

선의 의미: 대기시간 계수기가 타임 틱을 측정하고 에이징 정책에 의해 보정된 우선순위가 준비 큐 및 스케줄러로 반영되는 메카니즘.

| 구성요소 | 책임 |
|:---|:---|
| 대기시간 계수기 (Wait-Time Counter) | Ready Queue 진입 후 경과된 물리 대기 타임 슬라이스 누적 계산 |
| 에이징 정책 (Aging Policy) | 대기 주기 수 $\times$ **Aging Step** 기반 동적 우선순위 갱신 공식 인가 |
| 우선순위 준비 큐 (Priority Queue) | **Priority Ceiling** 수치 상한을 초과하지 않는 범위 내에서 갱신 노드 재배치 |
| OS 스케줄러 | 갱신된 우선순위 노드를 참조하여 최우선 프로세스 CPU 디스패치 |

$$\text{보정 우선순위} = \min(\text{기본 우선순위} + \text{대기 시간} \times \text{Aging Step}, \text{Priority Ceiling})$$

#### 한줄 요약

- 대기시간 계수와 에이징 정책 기반 우선순위 보정이 핵심이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Indefinite Blocking**: 기아 현상으로 인해 프로세스가 완료되지 못하고 무한 대기 상태에 처하는 장애 현상.

</details>

```text
┌──────────────────────────────┐
│ 준비 큐 진입                │
└──────────────┬───────────────┘
               ▼
╔══════════════════════════════╗
║ 반복: 해당 작업이 대기 중   ║
║                              ║
║ 1. 대기시간 누적            ║
║            │                 ║
║            ▼                 ║
║ 2. 상향 시점 판정           ║
║   ├─ 도래 ─▶ 3. 보정        ║
║   │            우선순위 계산║
║   │               │          ║
║   │               ▼          ║
║   │       4. 준비 큐 재정렬 ║
║   │               │          ║
║   └─ 미도래 ──────┤          ║
║                   ▼          ║
║ 5. 최고 우선순위 선택       ║
║   ├─ 다른 작업 ─▶ 반복      ║
║   └─ 해당 작업 ─▶ 반복 종료 ║
╚══════════════╤═══════════════╝
               ▼
         [작업 디스패치]
```

### 동작 원리

1. 대기시간 누적: Ready Queue 상주 프로세스의 **Wait-Time Counter** 틱 지속 합산.
2. 상향 시점 판정: 지정된 Aging 시간 간격($T$) 충족 여부 체크.
3. 보정 우선순위 계산: **Aging Step** 가산 및 **Priority Ceiling** 캡 씌우기 연산.
4. 준비 큐 재정렬: 갱신된 우선순위에 기반하여 Priority Queue 노드 위치 재정렬.
5. 최고 우선순위 선택: 승격된 프로세스가 최상위에 도달 시 스케줄러 디스패치 완결 (**Starvation 차단**).

#### 한줄 요약

- 대기가 지속되면 보정 우선순위 계산과 준비 큐 재정렬을 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Static Priority**: 프로세스 생성 시 부여된 우선순위가 종료 시까지 절대 변하지 않는 방식.

</details>

| 비교 항목 | Aging 기반 동적 우선순위 | Static Priority (정적 우선순위) |
|:---|:---|:---|
| 우선순위 변동 | 대기 시간에 비례하여 동적 격상 | 생명주기 동안 고정 유지 |
| 기아 대응 | 정책 상한 내 **최대 대기** 제한 가능 | 지속적인 고우선순위 유입 시 기아 가능 |
| 오버헤드 | 대기시간 계산과 큐 재정렬 | 우선순위 갱신 비용 없음 |
| 주요 활용 | 동적 우선순위 스케줄링 | 중요도가 고정된 작업군 |

#### 한줄 요약

- 최대 대기 제한은 에이징, 중요도 고정은 고정 방식이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Fair Share Scheduling**: 유저 또는 Cgroups 그룹 단위로 CPU 점유 지분을 분배하여 기아를 차단하는 스케줄링 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정적 우선순위 기반 스케줄링 시 저우선순위 프로세스 **Starvation** | **Aging** 기법 적용 (대기 시간 비례 가산) | 무한 대기 현상 차단 |
| 과도한 Aging 승격으로 커널/하드 실시간 작업 인가 차단 | **Priority Ceiling** 한계 수치 설정 | 시스템 마이크로 커널 보호 |
| 특정 유저의 대량 프로세스 생성을 통한 Aging 꼼수 | **Fair Share Scheduling (Cgroups)** 적용 | 그룹 간 공정성 확립 |

> 사례: Linux 커널 **CFS vruntime** 보정 및 Windows 커널 **Dynamic Priority Boost & Aging** 인프라 적용

#### 한줄 요약

- 상위 백분위 대기시간으로 에이징 강도를 조정한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Aging 파라미터 튜닝 기준(Aging Parameter Tuning Criteria)**: 타깃 응답시간, Aging Step, Priority Ceiling 및 공정성에 의거한 튜닝 체계.

</details>

- 최대 대기 보장이 필요하면 **Aging**, 고정 중요도면 **정적 우선순위** 선택

#### 한줄 요약

- 최대 대기와 긴급 작업 보호를 함께 만족하는 상향값을 설정한다.
