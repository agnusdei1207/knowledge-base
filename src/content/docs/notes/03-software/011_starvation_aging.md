## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기아 현상(Starvation)**: 고우선순위 프로세스의 연속 인입으로 저우선순위 프로세스가 CPU를 영구히 할당받지 못하고 무한 대기하는 현상.
- **에이징(Aging)**: 준비 큐에서 대기한 시간에 비례하여 프로세스의 우선순위를 점진적으로 높여 기아를 해소하는 동적 보정 기법.

</details>

- 정의/개념: 고우선순위 작업의 연속 인입으로 저우선순위 작업이 멈추는 **기아 현상**과 대기 시간에 비례해 우선순위를 높이는 **에이징(Aging)** 기법
- 배경/필요성: 정적 우선순위 기반 스케줄링 환경에서 고우선순위 작업의 연속 인입으로 인해 저우선순위 프로세스가 영구히 CPU를 할당받지 못하는 기아 현상(Starvation/Indefinite Blocking)을 극복하고, 준비 큐 대기 시간에 비례하여 우선순위를 점진적으로 승격시키는 에이징(Aging) 메커니즘을 통해 **모든 프로세스의 유한 시간 내 실행 보장(Fairness)과 시스템 기아 결함을 원천 해소**할 필요

#### 한줄 요약
- 대기 시간이 길어질수록 우선순위를 동적으로 승격시켜 무한 대기 기아 현상을 방지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **에이징 스텝(Aging Step)**: 대기 단위 시간당 우선순위를 가산하는 증가 폭.
- **우선순위 상한(Priority Ceiling)**: 에이징으로 승격 가능한 최대 우선순위 한계선(커널 실시간 영역 침범 방지용).

</details>

- 준비 큐 대기 시간 누적에 비례하여 **동적 우선순위 승격(Aging)** 수행
- **우선순위 상한선(Priority Ceiling)** 설정을 통한 커널 실시간(RT) 프로세스 영역 침범 방지
- **에이징 주기($\Delta t$) 및 스텝 크기** 조절을 통한 기아 해소 속도와 문맥 전환 오버헤드 간 균형

#### 한줄 요약
- 에이징은 기아를 없애는 대신 우선순위의 구속력을 시간에 따라 약화시키므로, 상한선은 그 약화가 긴급 작업까지 삼키지 않게 막는 장치가 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대기 시간 카운터(Wait Timer)**: 프로세스가 준비 큐에 진입한 후 경과한 틱(Tick) 수를 측정하는 타이머.

</details>

```text
[에이징 기반 동적 스케줄링 구조]
|-- 대기 시간 계측기 (Ready Queue 진입 후 틱 단위 대기 시간 카운트)
|-- 에이징 연산 엔진
|   |-- 승격 조건: 대기 시간 >= 에이징 주기 $\Delta t$
|   |-- 우선순위 연산: Priority = Priority + Aging Step
|   `-- 상한 보정: min(Priority, Priority Ceiling)
|-- 우선순위 준비 큐 (승격된 우선순위 기반 재정렬)
`-- 스케줄러 디스패처 (최고 우선순위 도달 프로세스 즉시 CPU 할당)
```

선의 의미: 계층 및 에이징 연산 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| 대기 시간 계측기 | 준비 큐에 머무는 프로세스의 **대기 시간(Wait Time)** 을 틱 단위로 정밀 누적 |
| 에이징 연산 엔진 | 주기 $\Delta t$마다 우선순위를 가산하고 **우선순위 상한(Priority Ceiling)** 내로 통제 |
| 우선순위 준비 큐 | 우선순위가 승격된 프로세스를 재정렬하여 상위 헤드로 배치 |
| 스케줄러 디스패처 | 승격되어 최상위에 도달한 저우선순위 프로세스에 CPU 제어권 이양 |

#### 한줄 요약
- 에이징 엔진이 우선순위 큐 바깥에서 대기 시간을 우선순위 값으로 환산해 주입하므로, 스케줄링 정책 자체를 바꾸지 않고도 기아만 걷어낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **무한 블로킹(Indefinite Blocking)**: 자원을 기다리는 프로세스가 스케줄러로부터 영구히 선택받지 못하는 결함 상태.

</details>

```text
저우선순위 프로세스 준비 큐 진입
        │
   하드웨어 타이머 인터럽트 발생 시 대기 시간 틱 누적
        │
   누적 대기 시간 >= 에이징 주기 $\Delta t$ 인가?
   ┌────┴─────┐
  예           아니오
   │             │
우선순위 승격     대기 상태 유지
(Priority += Step)│
   │             │
우선순위 상한(Ceiling) 초과 방지 보정
   │
준비 큐 내 정렬 위치 상위로 이동
   │
최고 우선순위 획득 후 디스패치 실행 (무한 블로킹 기아 해소)
```

#### 한줄 요약
- 틱 누적과 승격 검사가 주기마다 반복되는 부담이지만, 그 덕에 대기가 길수록 선택 확률이 오르는 방향으로 큐 순서가 스스로 교정된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Fair-Share 스케줄링**: 프로세스 개별이 아닌 사용자(User) 또는 그룹 단위로 CPU 지분을 분배하는 스케줄링.

</details>

| 비교 항목 | 에이징 기반 동적 우선순위 | 정적 우선순위 스케줄링 | CFS 가상 실행시간(vruntime) |
|:---|:---|:---|:---|
| 기아 현상 발생 | **원천 차단 (대기 시 승격)** | 발생 가능 (고우선순위 독점 시) | **원천 차단 (미실행 시 최소 vruntime)** |
| 우선순위 갱신 | 대기 시간 주기별 갱신 | 생성 시 영구 고정 | 실행 시마다 vruntime 누적 |
| 오버헤드 | 큐 재정렬 오버헤드 존재 | 오버헤드 전무 ($O(1)$) | 레드-블랙 트리 오버헤드 ($O(\log n)$) |
| 주 적용처 | 전통적 시분할 UNIX OS | 실시간 RTOS (결정론적 마감) | 현대 Linux 범용 스케줄러 |

#### 한줄 요약
- 기아 방지는 에이징과 CFS가 탁월하며, 정적 우선순위는 오버헤드가 없으나 기아 위험이 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **cgroup Shares**: 리눅스에서 프로세스 그룹 간 CPU 상대 가중치를 지정하여 공정 배분을 강제하는 제어 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 저우선순위 프로세스의 무한 대기 **기아 현상(Starvation)** | **에이징(Aging)** 주기적 우선순위 승격 적용 | 모든 프로세스의 유한 시간 내 실행 확정 보장 |
| 과도한 에이징으로 커널/실시간 태스크 우선순위 역전 | **우선순위 상한(Priority Ceiling)** 임계값 고정 | 실시간 제어 태스크의 마감시간 안전성 보존 |
| 특정 사용자의 프로세스 대량 생성으로 인한 CPU 독점 | **Fair-Share 스케줄링 및 cgroup CPU Shares** 할당 | 사용자/그룹별 CPU 공정 지분 강제 보장 |
| 잦은 우선순위 재계산으로 인한 스케줄러 오버헤드 | 에이징 검사 주기를 타임 퀀텀의 배수 단위(100ms)로 완화 | 큐 재정렬 연산 부하 80% 감소 |

#### 한줄 요약
- 에이징은 대기 시간을 우선순위로 환산해 기아를 없애지만 그만큼 원래 우선순위의 구속력을 약화시키므로, 우선순위 상한과 Fair-Share 지분으로 승격 폭을 제한해 긴급 작업의 우위를 남긴다.

## Ⅶ. 결론

- 우선순위 기반 운영체제 스케줄링 및 메시지 큐 시스템의 **핵심 공정성 보정 표준 알고리즘**으로 정립되었으며, 실무에서는 **저우선순위 기아 방지를 위한 틱 기반 에이징 승격과 더불어, 커널 실시간(RT) 마감시간 역전을 방지하는 우선순위 상한(Priority Ceiling) 제한 및 컨테이너 단위 Fair-Share(cgroups cpu.shares)**를 결합하여 운영 안정성을 확보

#### 한줄 요약
- 에이징은 대기 시간을 자원 획득 권한으로 치환하여 우선순위 기반 시스템의 기아 결함을 완벽히 보정하는 핵심 기법이다.
