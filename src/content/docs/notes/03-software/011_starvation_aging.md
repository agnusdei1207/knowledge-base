## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기아 현상(Starvation)**: 고우선순위 프로세스가 끊임없이 도착하여 저우선순위 프로세스가 CPU를 영구히 할당받지 못하는 무한 블로킹 상태.
- **동적 우선순위 승격(Aging)**: 준비 큐에서 대기한 시간에 비례하여 작업의 우선순위를 점진적으로 격상시키는 스케줄링 공정성 보정 기법.
- **영구 실행 불가(Indefinite Postponement)**: 스케줄러의 편향으로 인해 특정 태스크의 처리가 기약 없이 무한정 지연되는 시스템 결함.

</details>

- 정의/개념: 고우선순위 작업의 연속 유입 시 저우선순위 작업이 무한 대기하는 **기아 현상(Starvation)**을 대기 시간에 비례해 승격시키는 스케줄링 보정 기법
- 배경/필요성: 정적 우선순위 큐 구조에서 고우선순위 프로세스의 큐 독점으로 인한 **저우선순위 작업 영구 실행 불가 및 응답 정체** 직면

#### 한줄 요약

- 우선순위 스케줄링의 기아 현상을 대기 시간 비례 우선순위 상향(에이징)으로 해소하는 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우선순위 상한(Priority Ceiling)**: 에이징으로 우선순위가 상향될 수 있는 최대 한계값으로, 시스템·실시간 프로세스 영역 침범을 방지하는 상한.
- **에이징 스텝(Aging Step)**: 대기 시간 단위당 우선순위를 상향하는 가중치 계수.

</details>

- 대기 시간 누적에 비례하여 동적으로 우선순위를 격상하는 **에이징** 적용
- **우선순위 상한** 설정으로 시스템 코어 프로세스 우선순위 침범 방지
- **에이징 스텝** 크기와 **우선순위 상한**으로 기아 해소 속도와 시스템 안정성 간 균형 조정

#### 한줄 요약

- 대기 시간을 점수로 환산하여 우선순위를 상향하되, 시스템 프로세스 침범을 방지하는 상한 설정 병행

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대기 시간 계수기(Wait-Time Counter)**: 프로세스가 준비 큐에 진입한 이후 경과한 대기 시간을 누적 측정하는 커널 카운터.

</details>

```text
[ 에이징 동적 우선순위 조정 구조 ]
대기 시간 계수기 (Ready Queue 진입 후 경과 시간 누적)
   │
   ▼
에이징 정책
├─ 조건: 대기 시간 ≥ 에이징 주기
├─ 연산: 우선순위 += 에이징 스텝
└─ 상한: min(갱신 우선순위, 우선순위 상한)
   │
   ▼
우선순위 준비 큐 (갱신된 우선순위로 재정렬)
   │
   ▼
OS 스케줄러 (최고 우선순위 프로세스 CPU 이양)
```

선의 의미: 가지(`├─`, `└─`)는 에이징 정책의 조건·연산·상한 제약 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 대기 시간 계수기 | 프로세스별 준비 큐 **대기 시간** 누적 측정 |
| 에이징 정책 | **에이징 스텝** 적용 및 **우선순위 상한** 내 우선순위 상향 |
| 우선순위 준비 큐 | 갱신된 우선순위로 프로세스 재정렬 |
| OS 스케줄러 | 최고 우선순위 프로세스에 CPU 이양 |

#### 한줄 요약

- 대기 시간 계수기가 대기 시간을 측정하면 에이징 정책이 우선순위를 상향하고 큐가 재정렬

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **무한 블로킹(Indefinite Blocking)**: 기아 현상으로 프로세스가 준비 큐에서 CPU를 무한히 대기하는 상태.

</details>

```text
프로세스 준비 큐 진입
   │
   ▼
1. 대기 시간 틱 누적
   │
   ▼
2. 에이징 조건 판정 (대기 시간 ≥ 주기 T)
├─ 미충족: 대기 지속
└─ 충족
      │
      ▼
   3. 우선순위 += 에이징 스텝
      └─ min(결과, 우선순위 상한) 적용
      │
      ▼
   4. 준비 큐 재정렬
      │
      ▼
   5. 최고 우선순위 도달 → 스케줄러 선정 → CPU 이양
      (무한 블로킹 해소)
```

**동작 원리**

1. **대기 시간 누적**: 프로세스가 준비 큐에 진입한 후 틱 단위로 대기 시간을 누적
2. **에이징 조건 판정**: 정해진 에이징 주기마다 에이징 조건 충족 여부 확인
3. **우선순위 상향**: 에이징 스텝을 가산하되 우선순위 상한을 초과하지 않도록 제한
4. **큐 재정렬**: 갱신된 우선순위로 준비 큐를 재정렬하여 CPU 할당 순서 조정

#### 한줄 요약

- 주기마다 에이징 조건을 판정하고 우선순위를 상한 내에서 상향하여 무한 블로킹을 해소

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 우선순위(Static Priority)**: 생성 시 할당된 우선순위가 실행 종료까지 변경되지 않는 고정 우선순위 방식.

</details>

| 비교 항목 | 에이징 동적 우선순위 | 정적 우선순위 |
|:---|:---|:---|
| 적용 기준 | 기아 현상 방지 필요한 범용 멀티태스킹 환경 | 결정론적 마감 보장 필요한 실시간 환경 |
| 핵심 특징 | 대기 시간 비례 **에이징 스텝** 적용 동적 상향 | 생성 시 고정 우선순위, 변경 없음 |
| 한계 및 위험 | 주기적 재정렬로 스케줄링 오버헤드 증가 | 고우선순위 지속 도착 시 **기아 현상** 발생 |

#### 한줄 요약

- 기아 방지 필요 범용 환경은 에이징 동적 우선순위, 결정론적 마감 보장 실시간 환경은 정적 우선순위 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **공정 분배 스케줄링(Fair Share Scheduling)**: 사용자·그룹 단위로 CPU 할당량을 분배하여 대량 프로세스 생성을 통한 CPU 독점을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 저우선순위 프로세스의 **기아 현상** 발생 | **에이징** 기법 적용으로 대기 시간 비례 우선순위 상향 | 저우선순위 프로세스의 CPU 할당 보장 |
| 과도한 에이징으로 시스템 프로세스 우선순위 침범 | **우선순위 상한** 설정으로 에이징 최대값 제한 | 시스템 안정성 유지 |
| 대량 프로세스 생성으로 에이징 CPU 할당량 독점 | **공정 분배 스케줄링** (cgroup 기반) 적용 | 사용자 단위 CPU 할당 공정성 확보 |

#### 한줄 요약

- 기아는 에이징으로, 시스템 침범은 우선순위 상한으로, 독점은 공정 분배 스케줄링으로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **에이징 파라미터 튜닝 기준**: 에이징 스텝과 우선순위 상한을 조정하여 기아 해소 속도와 시스템 안정성 간 균형을 맞추는 판단 기준.

</details>

- 응답성 중시 범용 환경은 **에이징 동적 우선순위**, 결정론적 마감 보장 필요 실시간 환경은 **정적 우선순위** 선택

#### 한줄 요약

- 기아 방지와 응답성이 우선이면 에이징 동적 우선순위, 결정론적 마감이 우선이면 정적 우선순위를 적용
