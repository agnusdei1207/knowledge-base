## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NUMA(Non-Uniform Memory Access)**: CPU 소켓이 여러 개인 서버에서, CPU가 자기 앞마당(로컬 메모리)을 읽을 땐 존나 빠르지만 남의 앞마당(원격 메모리)을 읽을 땐 버스(QPI)를 타야 해서 느려터지는 하드웨어 구조이다.
- **NUMA 인지 스케줄링(NUMA-aware Scheduling)**: CPU가 딴 동네 메모리를 읽느라 병목 터지는 걸 막기 위해, OS가 스레드와 그놈이 쓸 메모리를 무조건 '같은 동네(NUMA 노드)'에 묶어버리는(바인딩) 똑똑한 스케줄링이다.

</details>

- 정의: 멀티소켓 NUMA 서버에서 스레드가 쓸 메모리를 무조건 로컬에 쑤셔 박아 원격 접근 지연을 찢어버리는 **NUMA 인지 스케줄링**
- 배경: 멍청하게 스케줄링하면 CPU는 0번 노드인데 메모리는 1번 노드에 할당돼서, 데이터 읽을 때마다 **인터커넥트 톨게이트 비용** 뜯기기 때문

#### 한줄 요약

- CPU가 남의 동네 메모리 읽느라 버벅이지 않게, 스레드와 메모리를 한 동네(노드)에 묶어버리는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **퍼스트 터치 정책(First-Touch Policy)**: 메모리를 "선언"할 때가 아니라, 진짜로 처음 "터치(Read/Write)"하는 놈의 CPU 동네(로컬 노드)에 물리 메모리를 꽂아버리는 리눅스의 국룰 할당 기법이다.
- **오토 누마(AutoNUMA)**: 스레드가 남의 동네 메모리만 주구장창 읽고 있으면, 리눅스가 백그라운드에서 눈치채고 아예 그 메모리를 내 동네로 강제 이주(Migration)시켜버리는 자동 최적화 엔진이다.

</details>

- 남의 메모리 건드리는(Remote Access) 짓을 혐오하고 무조건 **로컬 메모리 접근** 대상 목숨 걺.
- 생성할 땐 **퍼스트 터치(First-Touch)** 로 묶고, 돌다가 꼬이면 **AutoNUMA** 강제 이주시킴.
- 근데 한 동네(노드)에만 스레드가 몰리면 메모리가 꽉 차서 OOM 터지는 **메모리 불균형** 부작용이 있음.

#### 한줄 요약

- 퍼스트 터치로 내 동네에 메모리를 박고, 남의 걸 너무 많이 읽으면 AutoNUMA가 강제 이주시킨다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 누마(vNUMA)**: 가상머신(VM) 안에서도 "여긴 0번 노드, 저긴 1번 노드야"라고 뻥카를 쳐서, 게스트 OS가 NUMA 스케줄링을 돌릴 수 있게 하드웨어 구조를 노출하는 하이퍼바이저 기술이다.

</details>

```text
[ NUMA 아키텍처 및 스케줄링 십자포화 구조 ]

[ NUMA Node 0 ] ◀─── QPI/UPI ───▶ [ NUMA Node 1 ]
   (CPU 0)        (인터커넥트 버스)     (CPU 1)
      │             (원격 접근 시 딜레이)   │
[ 로컬 메모리 0 ]                 [ 로컬 메모리 1 ]
      ▲                                 ▲
      └─────── [ AutoNUMA ] ────────────┘
        (남의 거 계속 읽으면 아예 이주시켜버림)
```

| 구성요소 | 책임 |
|:---|:---|
| NUMA Node (노드) | CPU와 그놈 전용 고속 메모리가 한 세트로 묶인 동네 (자원 그룹) |
| Interconnect (UPI/QPI) | 0번 동네와 1번 동네를 잇는 고속도로. 여기를 타는 순간(원격 접근) 성능이 반토막 남 |
| **AutoNUMA Balancing** | 주기적으로 감시하다가, "너 왜 남의 거 계속 읽냐?" 싶으면 메모리를 내 동네로 **이주(Migration)** 시키는 깡패 |
| **`numactl`** | 관리자가 강력히 "넌 0번 노드에서만 돌아라" 하고 CPU와 메모리를 강제 **바인딩(Binding)** 하는 명령어 |

#### 한줄 요약

- 노드끼리는 느린 버스로 연결되어 있고, AutoNUMA와 numactl이 그 사이에서 메모리 이사를 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NUMA 힌트 폴트(NUMA Hint Fault)**: 리눅스가 꼼수를 써서 페이지 접근 권한을 막아놓고, 스레드가 거길 찌를 때 발생하는 에러(Fault) 횟수를 카운트해서 "이놈 남의 꺼 겁나 읽네!" 하고 잡아내는 모니터링 기술이다.

</details>

```text
[ AutoNUMA 스레드-메모리 이주 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 스레드 실행 및 퍼스트 터치│
│ (내 동네에 메모리 할당됨)    │
└──────────────┬───────────────┘
               ▼ (어쩌다 딴 동네로 스레드 튕김)
┌──────────────────────────────┐
│ 2. 권한 장난질 (PROT_NONE)   │
│ (OS가 메모리 접근권한 숨김)  │
└──────────────┬───────────────┘
               ▼ (접근 시도)
┌──────────────────────────────┐
│ 3. 힌트 폴트(Hint Fault) 발생│
│ (OS가 원격 억세스 카운트 잼) │
└──────────────┬───────────────┘
               ▼ (임계치 돌파)
┌──────────────────────────────┐
│ 4. 페이지/스레드 이주(Migrate)│
│ (메모리를 내 동네로 뜯어옴)  │
└──────────────────────────────┘
```

### 동작 원리

1. 토폴로지 파악 및 할당: `numactl`로 거리를 재고, 런타임에 **First-Touch** 기반 메모리를 배정함.
2. 트랩(함정) 설치: AutoNUMA가 일부러 페이지 권한을 뺏어서 접근 불가로 만듦.
3. Hint Fault 수집: 스레드가 원격 메모리를 찌르려다 Fault(트랩)에 걸리면, OS가 그걸 카운팅함.
4. 이주 편익 판정: "메모리 뜯어오는 복사 비용 vs 냅두고 계속 원격 찌르는 비용" 각을 잼.
5. 강제 이주(Migration): 뜯어오는 게 이득이면, 메모리 페이지를 통째로 로컬 노드로 복사해 옴.

#### 한줄 요약

- OS가 트랩을 파놓고 남의 메모리 읽는 횟수를 세다가, 선을 넘으면 통째로 복사해서 뜯어온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인터리브 정책(Interleave Policy)**: 노드 1개에 메모리가 빵 터지는 걸 막으려고, 메모리 할당을 0번, 1번, 0번, 1번 노드에 골고루 흩뿌려서 대역폭(Bandwidth)을 대폭 향상시키는 전략이다.

</details>

| 메모리 할당 정책 | 동작 방식 (어떻게 쑤셔 넣나) | 장단점 및 직관적 비교 |
|:---|:---|:---|
| **Local Node** (국룰) | 묻지도 따지지도 않고 처음 터치한 놈의 로컬 노드에 꽂음 | 딜레이 최소화엔 짱인데, 한 동네 메모리만 거덜 날 수 있음 |
| **Node Bind** (`numactl`) | 관리자가 강력히 "무조건 0번 노드에만 써!" 지정함 | 0번 메모리 다 차면 1번이 텅 비어있어도 **OOM 뿜고 죽어버림** |
| **Interleave** | 모든 동네(노드)에 라운드 로빈으로 골고루 흩뿌려 박음 | 딜레이는 느려도, 하둡/DB처럼 **대역폭 깡패**일 때 개꿀임 |

#### 한줄 요약

- 속도는 Local Node가 빠르지만 밸런스가 똥망이고, 대용량 대역폭은 Interleave가 씹어먹는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NUMA 노드 고갈(NUMA Node Memory Exhaustion)**: 0번 노드 메모리는 100% 꽉 차서 스왑 치고 난리 났는데, 1번 노드는 텅텅 비어서 놀고 있는 빡치는 불균형 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Local로 뒀더니 0번 메모리만 차서 **NUMA 노드 고갈** 기반 멈춤 | 오라클/PostgreSQL 구동 시 `numactl --interleave=all` 갈김 | 용량 빵빵하게 다 쓰고 대역폭 대폭 향상시켜서 불균형 박살 |
| AutoNUMA 켰더니 이사(Migration)하느라 CPU 처먹고 더 느려짐 | **`numactl --cpunodebind=0`** 기반 애초에 이사 못 가게 못 박음 | 스캔/복사 오버헤드 원천 봉쇄하고 철통같은 로컬 접근 사수 |
| 가상머신(VM) 올렸더니 호스트 NUMA 다 무시하고 똥망됨 | 하이퍼바이저에 **vNUMA** 활성화해서 게스트 OS한테 알려줌 | 게스트 OS가 "아 여긴 0번이구나" 깨닫고 자체 튜닝 돌림 |

#### 한줄 요약

- DB는 무조건 Interleave로 흩뿌리고, 이사 비용이 크면 Bind로 묶고, VM은 vNUMA를 켜줘라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NUMA 최적화 기준(NUMA Optimization Criteria)**: 메모리를 찔끔찔끔 빨리 읽어야 하는지(로컬), 용량 크고 콸콸 쏟아져야 하는지(인터리브) 각을 재는 튜닝 잣대이다.

</details>

- **NUMA 최적화 기준** 원칙에 따라, 응답속도 생명인 웹 서버는 **Local Bind**, 메모리 무식하게 처먹는 DBMS/빅데이터는 무조건 **Interleave** 채택 기조 확립함

#### 한줄 요약

- 초저지연 연산은 내 앞마당(Local/Bind)만 파고, 거대한 덩치(DB)는 모든 앞마당(Interleave)을 다 파먹어라.
