## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비균등 메모리 접근(Non-Uniform Memory Access, NUMA)**: 프로세서와 메모리가 노드 단위로 분할되어 접근 대상 노드의 위치에 따라 메모리 접근 지연 시간이 상이한 멀티프로세서 컴퓨터 아키텍처.
- **NUMA 인지 스케줄링(NUMA-aware Scheduling)**: 스레드가 실행되는 CPU 코어와 해당 스레드가 접근하는 물리 메모리를 동일 NUMA 노드에 배치하여 원격 메모리 접근 오버헤드를 최소화하는 운영체제 스케줄링 기법.

</details>

- 정의/개념: 다중 소켓 환경에서 스레드와 할당 메모리를 동일 노드에 배치하여 **원격 메모리 접근 지연** 최소화하는 운영체제 자원 스케줄링 기법
- 배경/필요성: 단일 UMA(Uniform Memory Access) 방식의 버스 대역폭 병목을 극복하기 위해 NUMA가 도입되었으나, 스레드와 메모리 노드 불일치 시 인터커넥트 전송 지연 발생

#### 한줄 요약
- 프로세서와 메모리 노드의 물리적 토폴로지를 인지하여 로컬 메모리 접근 비율을 극대화하는 스케줄링이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **퍼스트 터치 정책(First-Touch Policy)**: 가상 메모리 할당 시점이 아닌, 프로세스가 해당 메모리 페이지에 처음으로 읽기 또는 쓰기를 수행한 CPU가 속한 로컬 NUMA 노드에 물리 페이지를 할당하는 운영체제 정책.
- **자동 NUMA 밸런싱(AutoNUMA)**: 런타임에 원격 메모리 접근 패턴을 감지하여 메모리 페이지를 해당 스레드의 로컬 노드로 자동 이주(Migration)시키는 커널 서브시스템.

</details>

- **퍼스트 터치 정책(First-Touch Policy)** 기반의 초기 로컬 메모리 할당을 통한 인터커넥트 버스 부하 절감
- **자동 NUMA 밸런싱(AutoNUMA)** 메커니즘을 통한 동적 페이지 이주 및 스레드-메모리 친화도(Affinity) 유지
- 특정 노드의 메모리 고갈 시 다른 노드의 여유 메모리를 활용하거나 스왑이 발생하는 상충관계 존재

#### 한줄 요약
- 초기 할당 시 로컬 친화도를 부여하고, 런타임 접근 통계를 기반으로 동적 이주를 수행하여 지역성을 유지한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NUMA 노드(NUMA Node)**: 독립적인 CPU 코어 집합, 로컬 메모리 컨트롤러 및 물리 DRAM으로 구성된 하드웨어 자원 단위.
- **상호연결 인터커넥트(Interconnect)**: 서로 다른 NUMA 노드 간에 캐시 일관성 패킷과 원격 메모리 접근 데이터를 전달하는 고속 통신 링크(UPI, Infinity Fabric 등).
- **vNUMA(Virtual NUMA)**: 가상 머신(VM) 내부의 게스트 OS에 호스트의 물리 NUMA 토폴로지를 투영하여 게스트 수준 최적화를 가능하게 하는 가상화 기술.

</details>

```text
[ NUMA 노드 0 ] ◀────── 고속 인터커넥트 (UPI/QPI) ──────▶ [ NUMA 노드 1 ]
 ├─ CPU 코어 집합                                          ├─ CPU 코어 집합
 └─ 로컬 메모리 0                                          └─ 로컬 메모리 1
        ▲                                                         ▲
        └────────────── [ AutoNUMA 페이지 이주 ] ─────────────────┘
```

선의 의미: 양방향 화살표는 노드 간 인터커넥트 버스, 단방향 경로는 메모리 페이지 이주 경로

| 구성요소 | 책임 |
|:---|:---|
| **NUMA 노드** | CPU 코어와 로컬 메모리를 묶어 저지연 데이터 접근 단위 제공 |
| **인터커넥트(Interconnect)** | 노드 간 원격 메모리 접근 트랜잭션 및 일관성 패킷 전송 |
| **AutoNUMA 엔진** | 원격 힌트 폴트를 수집하여 페이지 및 스레드의 노드 간 이주 수행 |
| **numactl** | 사용자 공간에서 프로세스의 CPU 바인딩 및 메모리 할당 정책 강제 |

#### 한줄 요약
- 노드 내부의 로컬 버스와 노드 간 상호연결 인터커넥트로 구성되며, 제어 엔진을 통해 노드 간 메모리 배치를 조율한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NUMA 힌트 폴트(NUMA Hint Fault)**: 커널이 특정 메모리 페이지의 접근 권한을 일시적으로 제한(PROT_NONE)하여, 스레드가 접근할 때 발생하는 페이지 폴트를 통해 원격 접근 통계를 수집하는 기법.

</details>

```text
스레드 실행 및 메모리 할당
           │
           ▼
1. 퍼스트 터치 할당: 스레드를 실행 중인 로컬 NUMA 노드에 물리 메모리 할당
           │
           ▼
2. 힌트 폴트 모니터링: 커널이 페이지 권한을 PROT_NONE으로 설정해 원격 접근 추적
           │
           ▼
3. 접근 통계 수집: 스레드가 원격 메모리 접근 시 NUMA 힌트 폴트 발생 및 통계 기록
           │
           ▼
4. 이주 비용 대비 편익 분석: 원격 접근 빈도와 페이지 복사 오버헤드 비교 판정
           │
           ▼
5. 페이지/스레드 이주: 로컬 노드로 페이지를 물리 복사하거나 스레드를 대상 노드로 재스케줄링
```

**동작 원리**

1. **퍼스트 터치 할당**: 스레드가 메모리를 최초로 참조할 때 실행 중인 CPU의 로컬 노드에 물리 페이지 할당
2. **힌트 폴트 모니터링**: 커널 백그라운드 스레드가 주기적으로 대상 페이지의 접근 권한을 제한하여 트랩 설정
3. **접근 통계 수집**: 스레드가 해당 페이지에 접근할 때 힌트 폴트가 유발되어 원격 접근 횟수 누적
4. **이주 편익 분석**: 페이지 복사 비용 대비 원격 지연 시간 감소 이득을 계산하여 이주 여부 결정
5. **페이지/스레드 이주**: 편익이 큰 경우 페이지를 대상 로컬 메모리로 물리 복사하여 지역성 복원

#### 한줄 요약
- 힌트 폴트로 원격 메모리 접근 빈도를 계측하고, 비용 편익 분석을 거쳐 페이지를 로컬 노드로 이주한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인터리브 정책(Interleave Policy)**: 메모리 할당 요청을 전체 NUMA 노드에 라운드 로빈 방식으로 균등 분산하여 단일 노드 병목을 방지하는 메모리 할당 정책.

</details>

| 메모리 할당 정책 | Local Node (기본) | Node Bind (강제) | Interleave (인터리브) |
|:---|:---|:---|:---|
| **적용 기준** | 단일 스레드 작업, 캐시 지역성 중요 워크로드 | 전용 코어/메모리 격리가 필요한 실시간 시스템 | 대규모 공유 메모리 DBMS, 빅데이터 분석 |
| **핵심 특징** | 요청 CPU의 로컬 노드 우선 할당 | 지정된 특정 NUMA 노드 집합에만 메모리 할당 | 모든 NUMA 노드에 페이지를 라운드 로빈 분산 할당 |
| **한계** | 특정 노드 메모리 집중 시 불균형 및 스왑 발생 | 지정 노드 용량 초과 시 타 노드 여유와 무관하게 OOM 유발 | 모든 접근의 평균 지연 시간 증가 및 캐시 적중률 감소 |

#### 한줄 요약
- 지연 시간 최소화가 중요하면 로컬/바인딩 정책을, 대역폭 분산과 메모리 균형이 중요하면 인터리브 정책을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NUMA 노드 메모리 고갈**: 특정 NUMA 노드의 메모리가 소진되어 시스템 전체에 여유 메모리가 있음에도 스왑이 발생하거나 OOM 킬러가 동작하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특정 노드 메모리 소진으로 인한 조기 스왑 발생 | 대규모 메모리 점유 프로세스에 **`numactl --interleave=all`** 적용 | 노드 간 메모리 사용률 균등 분산 및 대역폭 확장 |
| AutoNUMA의 과도한 페이지 스캔 및 복사 오버헤드 | 코어 전용 작업에 **`numactl --cpunodebind`** 로 스레드-메모리 고정 | 런타임 이주 오버헤드 제거 및 일관된 실행 시간 보장 |
| 가상화 게스트 OS의 물리 NUMA 토폴로지 미인지로 인한 성능 저하 | 하이퍼바이저 수준에서 **vNUMA** 활성화 및 가상 소켓-노드 매핑 | 게스트 OS 스케줄러의 로컬 메모리 인지 최적화 수행 |

#### 한줄 요약
- 워크로드 특성에 따라 인터리브 분산, 정적 노드 바인딩, vNUMA 토폴로지 투영을 선별 적용한다.

## Ⅶ. 결론

- 저지연 응답이 요구되는 단일 인스턴스 워크로드는 **Node Bind**를 통해 로컬 지역성을 극대화하고, 대용량 메모리 병렬 처리가 요구되는 데이터베이스 및 분산 플랫폼은 **Interleave** 정책을 채택하여 시스템 전반의 대역폭과 메모리 균형을 달성

#### 한줄 요약
- 작업의 지연 시간 민감도와 메모리 규모를 기준으로 로컬 바인딩과 인터리브 분산 정책을 결정한다.
