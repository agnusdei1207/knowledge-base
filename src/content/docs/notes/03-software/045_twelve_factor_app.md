## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **무상태 및 환경 설정(Stateless & Config in ENV)**: 프로세스에 세션을 남기지 않고 외부 저장소로 분리하며 배포 환경별 설정을 OS 환경변수로 주입하는 클라우드 설계 원칙.
- **수평 확장 불가 및 환경 불일치(Scale-Out Failure & Parity Loss)**: 로컬 파일시스템에 종속되어 컨테이너 다중화가 불가능하고 개발/운영 환경 간 설정 차이로 장애가 발생하는 문제.

</details>

- 정의/개념: 클라우드 플랫폼에서 이식성·확장성을 극대화하기 위해 **무상태(Stateless), 환경변수 설정(Config), 선언적 의존성** 등 12개 방법론을 정의한 소프트웨어 공학 지침
- 배경/필요성: 서버 로컬 디렉터리에 상태와 설정을 바인딩하는 레거시 패턴으로 인한 **수평 확장(Scale-Out) 불가 및 환경 불일치 장애** 직면

#### 한줄 요약

- 컨테이너 기반 수평 확장·자동 복구를 지원하는 클라우드 네이티브 애플리케이션 개발 12가지 원칙

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **개발/운영 동등성(Dev/Prod Parity)**: 개발·스테이징·운영 환경의 기술 스택과 서비스를 동일하게 유지하여 환경 차이로 인한 운영 장애를 예방하는 원칙.
- **폐기 가능성(Disposability)**: 프로세스가 빠르게 시작(Fast Startup)되고 SIGTERM 수신 시 진행 중인 요청을 완료하고 안전하게 종료(Graceful Shutdown)되는 설계 원칙.

</details>

- 설정(DB 접속 정보·API 키)을 코드에서 분리하여 **환경 변수(ENV)** 로 주입
- 프로세스를 **무상태(Stateless)** 로 설계하여 언제든 재시작·복제·종료 가능한 수평 확장 구조 확보
- 개발/운영 환경 동등성과 신속한 시작·우아한 종료(**Disposability**) 준수

#### 한줄 요약

- 설정의 환경 변수 분리·프로세스 무상태 설계·개발/운영 환경 동등성으로 클라우드 최적화 달성

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **지원 서비스(Backing Services)**: DB·메시지 큐·캐시·이메일 서버 등 애플리케이션이 의존하는 외부 서비스를 URL 변경만으로 교체 가능한 탈부착 자원으로 취급하는 원칙.

</details>

```text
[ 12 팩터 클라우드 네이티브 구조 ]
단일 Git 코드베이스
   │
빌드(Build) → 릴리스(Release, ENV 주입) → 실행(Run)
                                              │
프로세스 (Stateless, 수평 확장·수축)
                                              │
지원 서비스 (DB·Redis·S3, 탈부착 가능)
```

선의 의미: 빌드→릴리스→실행 단계는 분리 불가 혼합 금지 원칙을 나타내며, 지원 서비스는 URL 교체로 탈부착 가능한 외부 의존 자원

| 12 팩터 주요 원칙 | 내용 |
|:---|:---|
| 1. **코드베이스(Codebase)** | 단일 Git 레포로 관리, 복수 배포 환경에 동일 코드 배포 |
| 3. **설정(Config)** | DB 접속 정보·API 키를 코드에서 분리하여 환경 변수로 주입 |
| 4. **지원 서비스(Backing Services)** | DB·Redis 등 외부 서비스를 URL 변경으로 교체 가능한 탈부착 자원 취급 |
| 6. **프로세스(Processes)** | 무상태(Stateless) 설계, 세션·파일은 외부 저장소 사용 |
| 11. **로그(Logs)** | 로그를 파일이 아닌 표준 출력(stdout)으로 배출하여 외부에서 수집 |

#### 한줄 요약

- 단일 코드베이스·ENV 설정 주입·무상태 프로세스·stdout 로그가 12 팩터의 핵심 원칙

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **빌드-릴리스-실행 분리(Build-Release-Run Pipeline)**: 코드 컴파일(빌드)·환경 설정 결합(릴리스)·프로세스 실행(실행)의 3단계를 명확히 분리하여 불변(Immutable) 배포 단위를 보장하는 원칙.

</details>

```text
1. 단일 Git 코드베이스 (Codebase)
   │
   ▼
2. 빌드 (Build): 코드 컴파일·의존성 설치→불변 컨테이너 이미지 생성
   │
   ▼
3. 릴리스 (Release): 빌드 이미지 + 환경 변수(ENV) 결합
   │
   ▼
4. 실행 (Run): Stateless 프로세스로 컨테이너 기동·수평 확장·자동 복구
   └─ 지원 서비스 (DB·Redis·S3)는 URL 기반 탈부착
```

**동작 원리** 1. **코드베이스**: 단일 Git 레포에서 소스를 관리하고 환경별 브랜치 분리 없이 ENV로 환경 구분
2. **빌드**: 코드와 의존성을 컴파일하여 불변 컨테이너 이미지를 생성
3. **릴리스**: 이미지에 환경 변수(DB URL·API Key)를 주입하여 배포 단위를 생성
4. **실행**: Stateless 컨테이너로 기동하고 K8s가 자동으로 수평 확장·복구 수행

#### 한줄 요약

- 빌드→릴리스(ENV 주입)→실행(Stateless)의 3단계를 분리하여 불변 배포 단위와 수평 확장성을 확보

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **레거시 vs 12 팩터 앱**: 상태·설정을 서버 로컬에 보관하여 확장 불가능한 레거시와 ENV·Stateless·stdout으로 언제든 확장·재시작이 가능한 12 팩터 앱의 대비.

</details>

| 구분 | 레거시 앱 | 12 팩터 앱 |
|:---|:---|:---|
| 설정 관리 | 소스 코드·설정 파일에 하드코딩 | **OS 환경 변수(ENV)** 외부 주입 |
| 세션·상태 | 서버 로컬 메모리에 세션 저장 | **무상태(Stateless)**, 세션은 Redis 등 외부 저장 |
| 로그 처리 | 서버 파일 시스템에 로그 파일 저장 | **stdout** 배출, 외부 수집 플랫폼 수집 |
| 스케일 방식 | 수직 확장(Scale-up)·수작업 | **수평 확장(Scale-out)**·자동화 |

#### 한줄 요약

- 레거시는 서버 로컬에 상태·설정을 보관하여 확장이 불가능하고, 12 팩터는 ENV·Stateless·stdout으로 수평 확장을 지원

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우아한 종료(Graceful Shutdown)**: SIGTERM 신호 수신 시 진행 중인 요청을 완료하고 DB 커넥션을 정리한 후 프로세스를 종료하여 데이터 유실을 방지하는 종료 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소스 코드에 DB 접속 정보 포함으로 보안 취약점 발생 | 설정을 소스에서 분리하여 **환경 변수(ENV)** 또는 시크릿 관리 도구 적용 | 소스 코드 노출 시 보안 자격 증명 보호 |
| 컨테이너 종료 시 처리 중인 요청 데이터 유실 | SIGTERM 핸들러로 **Graceful Shutdown** 구현 | 컨테이너 재시작 중 요청 유실 방지 |
| 컨테이너 종료 후 컨테이너 내부 로그 파일 소실 | 로그를 **stdout** 기반 배출하여 외부 로그 수집 플랫폼(ELK·Datadog)에 저장 | 컨테이너 종료 후에도 로그 보존 |

#### 한줄 요약

- 설정은 ENV로 분리하고, 종료는 Graceful Shutdown으로, 로그는 stdout으로 외부 수집하여 클라우드 운영성 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **클라우드 네이티브 도입 기준**: 수평 확장·자동 복구 필요 여부·컨테이너 기반 배포 여부를 기준으로 12 팩터 준수 수준을 결정하는 판단 기준.

</details>

- 컨테이너(K8s) 기반 수평 확장·자동 복구가 필요한 서비스는 **12 팩터 앱** 원칙 전면 준수

#### 한줄 요약

- 클라우드 인프라(K8s)를 활용하여 수평 확장·자동 복구를 실현하려면 12 팩터 원칙을 전면 준수
