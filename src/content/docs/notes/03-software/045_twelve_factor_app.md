## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **열두 팩터 앱(12 Factor App)**: 클라우드 애플리케이션의 반복 배포•수평 확장•인스턴스 교체를 위한 열두 가지 설계 원칙이다.
- **수평 확장(Horizontal Scaling)**: 같은 프로세스 인스턴스 수를 늘려 요청을 병렬 처리하는 확장 방식이다.

</details>

- 정의/개념: **열두 팩터 앱**은 클라우드 애플리케이션을 반복 배포하고 **수평 확장**하기 위한 설계 원칙이다.
- 배경/필요성: 서버별 설정•상태 결합은 재배포와 수평 확장을 제약한다.

#### 한줄 요약

- 상태•설정 외부화를 통한 **열두 팩터 앱**과 **수평 확장**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **코드베이스(Codebase)**: 버전 관리되는 하나의 원본에서 여러 환경의 배포를 만드는 기반이다.
- **의존성(Dependencies)**: 실행에 필요한 라이브러리를 명시적으로 선언하고 격리한 목록이다.
- **무상태 프로세스(Stateless Processes)**: 영구 데이터를 외부 지원 서비스에 보관해 서로 상태를 공유하지 않는 실행 단위이다.
- **개발•운영 환경 동등성(Development/Production Parity, Dev/Prod Parity)**: 개발•스테이징•운영 환경의 차이를 최소화하는 원칙이다.

</details>

- **코드베이스**와 **의존성**을 명시해 빌드를 재현한다.
- **무상태 프로세스**로 수평 확장•교체가 핵심이다.
- **개발•운영 환경 동등성**으로 같은 릴리스를 승격한다.

#### 한줄 요약

- **의존성**, **무상태 프로세스**, **개발•운영 환경 동등성**이 재현성을 만든다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **설정(Config)**: 자격 증명•주소처럼 배포 환경마다 달라 코드 밖에서 주입하는 값이다.
- **지원 서비스(Backing Services)**: 데이터베이스•메시지 큐•캐시처럼 연결 자원으로 취급하는 외부 서비스이다.
- **빌드(Build)**: 코드를 실행 가능한 산출물로 만드는 단계이다.
- **릴리스(Release)**: 빌드와 환경 설정을 결합하는 단계이다.
- **실행(Run)**: 릴리스의 프로세스를 시작하는 단계이다.
- **포트 바인딩(Port Binding)**: 애플리케이션이 직접 포트를 열어 서비스를 공개하는 방식이다.
- **프로세스(Process)**: 기능별로 정의한 무상태 실행 단위이다.
- **동시성(Concurrency)**: 프로세스 인스턴스 수를 늘려 부하를 처리하는 원칙이다.
- **폐기 가능성(Disposability)**: 프로세스를 빠르고 안전하게 시작하고 종료하는 성질이다.
- **관리 프로세스(Admin Processes)**: 일회성 운영 작업을 릴리스 환경에서 실행하는 프로세스이다.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 코드베이스•의존성 | 버전 관리 코드베이스•의존성 명시 |
| 설정•지원 서비스 | **설정** 주입과 **지원 서비스**로 영구 상태 외부화 |
| 빌드•릴리스•실행 | **빌드**•**릴리스**•**실행** 단계 분리 |
| 프로세스•동시성 | **프로세스**•**포트 바인딩**•**동시성**으로 수평 확장 |
| 폐기•로그•관리 작업 | **폐기 가능성**과 **관리 프로세스** 통제 |

```text
[코드베이스•의존성]
          |
[빌드•릴리스•실행] --- [설정•지원 서비스]
          |
  [프로세스•동시성]
          |
[폐기•로그•관리 작업]
```

선의 의미: 세로선은 코드 산출물의 생성•실행•운영 관계, 가로선은 릴리스와 외부 설정•지원 서비스의 결합 관계를 뜻한다.

#### 한줄 요약

- **설정**, **지원 서비스**, **빌드**, **릴리스**, **실행**, **프로세스**의 책임 분리가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **불변 빌드(Immutable Build)**: 생성 뒤 내용을 바꾸지 않고 같은 산출물을 환경별 설정과 결합해 승격하는 실행 묶음이다.
- **환경 설정 결합**: 불변 빌드에 배포 환경별 설정을 주입해 릴리스를 만드는 동작이다.
- **로그 스트림(Log Stream)**: 로그를 로컬 파일로 관리하지 않고 표준 출력의 이벤트 흐름으로 내보내는 방식이다.
- **릴리스 승격(Promotion)**: 검증한 동일 빌드를 설정만 바꿔 상위 환경에 배포하는 과정이다.
- **무상태 프로세스 확장**: 외부 상태를 공유하는 동일 프로세스 인스턴스를 늘리는 동작이다.
- **지원 서비스 연결•로그 외부화**: 영구 상태는 외부 자원에 맡기고 출력은 이벤트 흐름으로 전달하는 동작이다.

</details>

```text
[코드•의존성 변경]
         |
         v
+--------------------------+
| 1. 불변 빌드             |
+--------------------------+
         |
         v
+--------------------------+
| 2. 환경 설정 결합        |
+--------------------------+
         |
         v
+--------------------------+
| 3. 릴리스 승격           |
+--------------------------+
         |
         v
+--------------------------+
| 4. 무상태 프로세스 확장  |
+--------------------------+
         |
         v
+--------------------------+
| 5. 지원 서비스 연결•     |
|    로그 외부화            |
+--------------------------+
         |
         v
[반복 배포•교체 가능한 실행 환경]
```

**동작 원리**

1. **불변 빌드**로 코드와 의존성을 변경 불가능하게 보관한다.
2. **환경 설정 결합**으로 같은 빌드에 배포별 설정만 주입한다.
3. **릴리스 승격**으로 검증한 릴리스를 상위 환경에 배포한다.
4. **무상태 프로세스 확장**으로 동일 실행 인스턴스를 증설한다.
5. **지원 서비스 연결•로그 외부화**로 상태와 **로그 스트림**을 분리한다.

#### 한줄 요약

- **릴리스 승격**과 **무상태 프로세스 확장** 흐름이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **서버 결합형 앱**: 설정•설치•실행 상태를 특정 서버에 보존해 교체와 확장이 어려운 운영 구조이다.
- **상태 외부화**: 세션과 영구 데이터를 프로세스 밖의 공유 지원 서비스에 저장하는 방식이다.

</details>

| 애플리케이션 운영 구조 | 12 팩터 앱 | 서버 결합형 앱 |
|:---|:---|:---|
| 적용 기준 | 반복 배포•환경 이동•수평 확장 | 고정 서버•드문 배포 |
| 핵심 특징 | **상태 외부화**•불변 빌드•설정 주입 | **서버 결합형 앱**의 서버 상태•설정•설치 결합 |
| 한계 | 외부 자원 의존•상태 이전 | 서버 편차•교체•확장 복잡도 |

> 요약: **반복 배포•수평 확장** 필요성으로 운영 구조를 선택한다.

#### 한줄 요약

- 반복 배포•수평 확장은 **12 팩터 앱**을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **자격 증명(Credential)**: 데이터베이스 비밀번호•접근 키처럼 지원 서비스 접근 권한을 증명하는 비밀값이다.
- **세션 외부화(Session Externalization)**: 사용자 상태를 공유 지원 서비스에 저장해 어느 복제 프로세스도 요청을 처리하게 하는 방식이다.
- **정상 종료(Graceful Shutdown)**: 새 요청을 막고 진행 작업을 마친 뒤 자원을 해제해 프로세스를 안전하게 교체하는 방식이다.
- **비밀 저장소(Secret Store)**: 자격 증명을 암호화해 별도로 관리하는 저장소이다.
- **노출 검사(Exposure Scan)**: 코드와 이미지 및 로그의 비밀값 포함 여부를 검사하는 통제이다.
- **배포 재현성(Deployment Reproducibility)**: 같은 빌드와 설정으로 반복 배포했을 때 동일한 실행 결과를 만들 수 있는 성질이다.
- **종료 시간 제한(Shutdown Timeout)**: 정상 종료가 진행 작업을 기다릴 수 있는 최대 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비밀값을 코드•이미지•로그에 포함 | 설정 외부 주입•**비밀 저장소**•**노출 검사** | **자격 증명** 유출 방지 |
| 프로세스 로컬 세션•파일로 수평 확장 실패 | **세션 외부화**로 영구 데이터를 지원 서비스에 저장 | 모든 인스턴스의 요청 처리 허용 |
| 환경마다 다른 빌드를 다시 생성 | 검증한 불변 빌드를 설정만 바꿔 승격 | **배포 재현성** 확보 |
| 종료 신호로 즉시 종료해 요청•메시지 유실 | **정상 종료**와 **종료 시간 제한** 적용 | 안전한 프로세스 교체 |
| 관리 작업이 운영 코드•설정과 다름 | 같은 릴리스•자격 증명으로 일회성 작업 실행 | 이관 결과 일관성 확보 |

#### 한줄 요약

- **세션 외부화**, **정상 종료**, **배포 재현성**을 확보한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **설정 외부화**: 배포마다 달라지는 설정을 코드와 빌드 밖에서 주입하는 원칙이다.
- **반복 배포**: 동일한 코드와 불변 빌드를 여러 환경과 인스턴스에 재현 가능하게 배포하는 능력이다.
- **12 팩터 앱 적용 기준**: 반복 배포와 수평 확장 요구를 비교해 상태•설정 외부화 원칙의 적용 수준을 정하는 기준이다.

</details>

- **반복 배포**와 **수평 확장**이 필요하면 **설정 외부화**를 적용한 **12 팩터 앱**을 선택하는 것이 **12 팩터 앱 적용 기준**이다.

#### 한줄 요약

- 반복 배포와 수평 확장 요구를 함께 평가하는 것이 핵심이다.
