## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소버린 클라우드(Sovereign Cloud)**: 데이터의 물리적 저장 위치뿐만 아니라 운영자 신원과 암호키 통제권까지 현지 법률 관할권 내에 완전히 종속시키는 독립 클라우드.
- **3대 주권 축**: Data Sovereignty(데이터 저장 주권), Operational Sovereignty(운영 인력 주권), Technical Sovereignty(암호키/소프트웨어 기술 주권).

</details>

- 정의/개념: 데이터의 물리적 저장 위치, 운영 권한, 암호화 키를 자국 법률 관할권 내에 독립적으로 격리하고 통제하는 주권형 클라우드 아키텍처
- 배경/필요성: 글로벌 CSP 의존 시 외국의 사법 관할권 발동(미 CLOUD Act 등)에 따른 공공·금융 기밀 데이터 강제 징발 위험 및 기술 종속(Digital Colonialism) 한계

#### 한줄 요약
- 데이터 거주성, 현지 운영 인력, 외부 암호키를 결합하여 외국의 법적 간섭으로부터 데이터 주권을 수호한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **HYOK(Hold Your Own Key)**: 암호키를 클라우드 외부의 자체 온프레미스 HSM 장비에만 보관하여 CSP가 절대 데이터를 복호화하지 못하게 차단하는 모델.
- **CLOUD Act**: 미국 정부가 자국 CSP에게 해외 리전에 저장된 데이터라도 범죄 수사 목적으로 제출을 명령할 수 있는 법률.

</details>

- 원본 데이터 및 백업의 국외 반출을 엄격히 금지하는 데이터 거주성(Data Residency)
- 해외 CSP 본사 엔지니어의 원격 접속을 차단하고 현지 인력만 운영하는 운영 주권 통제
- 자체 독립 HSM 장비 기반의 외부 암호화 키 독점 통제(External KMS / HYOK)

#### 한줄 요약
- 데이터 거주성, 운영 인력 국적 제한, 고객 단독 외부 암호키를 통해 디지털 주권을 완성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **소버린 클라우드 3대 방어 계층**: Data Layer(자국 리전 저장), Operational Layer(인가된 현지 인력 전담), Key Layer(외부 자체 HSM 연동).

</details>

```text
[소버린 클라우드 주권 방어 아키텍처 구조]
|-- 데이터 거주성 (Residency)
|   |-- 국내 리전 전용 물리적 데이터 격리 저장
|   `-- 국외 데이터 전송 Egress 원천 차단
|-- 운영 주권 (Operational)
|   |-- 현지 자국 국적 보안 인가 인력 전담
|   `-- 글로벌 CSP 본사 원격 접근 차단
|-- 키 주권 (Key Sovereignty)
|   `-- 온프레미스 HSM 연동 암호키 독점 통제 (HYOK)
`-- 탈출 전략 (Exit Strategy)
    `-- K8s 등 오픈소스 표준 기반 벤더 비종속 타 플랫폼 이관
```

선의 의미: 계층 및 데이터 저장 위치, 운영자 인력 격리, 외부 암호키 제어가 계층적으로 결합되어 주권을 방어하는 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 데이터 거주성 (Residency) | 원본 데이터, 로그, 백업 복제본을 반드시 국내 지정 데이터센터에 물리적 격리 저장 | 물리적 국경 내 보관 |
| 운영 주권 (Operational) | 자국 국적의 인가된 인력만 인프라에 접근하며 글로벌 CSP 직원의 원격 접근 통제 | 현지 인력 전담 |
| 키 주권 (Key Sovereignty) | 사내 온프레미스 HSM을 통해 암호키 생성/폐기/사용 권한을 고객이 독점 행사 | External KMS / HYOK |
| 탈출 전략 (Exit Strategy) | 컨테이너 및 오픈소스 표준을 준수하여 유사시 타 클라우드로 무손실 즉각 이관 보장 | 벤더 비종속 오픈소스 |

#### 한줄 요약
- 거주성·운영·키 세 주권이 각각 다른 통제 지점을 잡고 있어 한 축만 충족해도 나머지 축에 열람 경로가 남으며, 탈출 전략은 그 통제가 무력화됐을 때의 퇴로를 맡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소버린 데이터 복호화 5단계**: 접근 요청 접수 $\to$ 운영자 국적/인가 검증 $\to$ 외부 고객 HSM 키 요청 $\to$ 승인 후 데이터 복호화 $\to$ 위변조 불가 감사 기록.

</details>

```text
소버린 클라우드 내 민감 데이터 조회 요청
        │
   1. [접근 요청 접수] 사용자가 자국 내 소버린 리전에 저장된 민감 데이터 조회 요청
        │
   2. [운영자 신원 검증] 로컬 IAM이 접근자의 국적과 사내 보안 인가 등급 검증
        │
   3. [외부 HSM 키 요청] 고객 소유의 온프레미스 외부 KMS(AWS XKS)로 복호화 키 요청
        │
   4. [정책 승인 복호화] 고객 측 정책 엔진 승인 시 메모리 상에서 데이터 복호화 수행
        │
   5. [감사 기록] 요청자, 사유, 타임스탬프를 WORM 스토리지에 위변조 불가 기록
```

#### 한줄 요약
- 복호화 권한이 CSP가 아닌 고객 HSM에 있어 모든 접근이 매번 고객 정책을 통과해야 하므로, 데이터가 CSP 인프라에 놓여도 열람 시점의 통제권은 고객에게 남는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Data Residency vs Sovereign Cloud**: 단순 물리적 저장소 위치 고정(Residency)과 운영권/암호키까지 관할권 내 통제(Sovereign).

</details>

| 비교 항목 | 단순 데이터 거주성 (Data Residency) | 완전한 소버린 클라우드 (Sovereign Cloud) |
|:---|:---|:---|
| 데이터 저장 위치 | 국내 리전에 물리적 저장 | 국내 리전에 물리적 격리 저장 |
| 운영 인력 국적 | 글로벌 CSP 해외 엔지니어가 원격 운영 | 현지 법인 소속 자국 보안 인가 인력 전담 |
| 암호키 통제 주체 | CSP 관리형 KMS (CSP가 키 보유) | 고객 온프레미스 HSM 독점 보관 (HYOK) |
| 외국 법률 징발 대응 | 미 CLOUD Act 발동 시 데이터 제출 불가피 | 기술적·법적으로 외국 정부 징발 원천 차단 |

#### 한줄 요약
- 단순 위치 규제는 데이터 거주성, 최고 수준의 국가 안보 및 데이터 주권은 소버린 클라우드를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **AWS XKS(External Key Store)**: AWS 외부의 물리적 HSM 장비와 연동하여 AWS가 암호화 키 원본에 일체 접근하지 못하게 차단하는 솔루션.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CSP 관리형 KMS 사용 시 백도어 및 강제 데이터 징발 위험 | AWS XKS / Google EKM 기반 온프레미스 Thales HSM 연동 | CSP의 데이터 열람 원천 차단 |
| 특정 CSP 독점 PaaS 종속으로 인한 벤더 락인 및 탈출 불가 | Kubernetes 및 오픈소스 PostgreSQL 기반 인프라 표준화 | 유사시 즉각적인 타 플랫폼 이관 보장 |
| 전면 소버린 클라우드 구축 시 막대한 인프라 구축 비용 발생 | 데이터 등급제 수립 후 1급 기밀 데이터만 선별 적용 | 주권 보장과 비용 효율성의 최적 절충 |
| 해외 CSP 리전 간 백업 복제 시 국경 이탈 사고 | CSP 리전 간 복제를 차단하고 국내 Multi-AZ 백업만 허용 | 데이터 국외 반출 원천 방지 |

#### 한줄 요약
- 네 대책은 CSP가 제공하는 관리 편의와 독점 PaaS의 생산성을 포기해 통제권을 되찾는 선택이며, 등급제 선별 적용은 완전한 주권 대신 구축 비용을 아끼는 절충이다.

## Ⅶ. 결론

- 글로벌 지정학적 갈등 심화와 국가별 데이터 주권 규제(EU Gaia-X, 국내 망분리/공공 CSAP) 강화에 대응하는 가장 핵심적인 차세대 엔터프라이즈 및 공공 클라우드 전략으로 부상하였으며, 실무 구축 시에는 CSP의 원천 데이터 열람을 기술적으로 차단하는 온프레미스 HSM 연동 외부 키 저장소(AWS XKS/Google EKM - HYOK), 현지 인가 인력 전담 운영, 벤더 종속을 탈피하는 K8s 오픈소스 기반 탈출 전략(Exit Strategy), 민감도별 데이터 등급제 선별 적용을 결합하여 클라우드의 혁신성과 국가 수준의 보안 주권을 완벽히 조화

#### 한줄 요약
- 소버린 클라우드는 데이터 거주성, 현지 운영권, 외부 암호키 독점을 통해 외국의 법적 간섭을 원천 차단하고 디지털 주권을 수호하는 핵심 클라우드 아키텍처다.
