## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소버린 클라우드(Sovereign Cloud)**: 데이터의 물리적 저장 위치(Data Residency)뿐만 아니라, 시스템 운영자 신원(Operational Sovereignty)과 암호화 키 통제권(Key Sovereignty)까지 현지 법률 관할권(Local Jurisdiction) 내에 완전히 종속시키는 독립형 클라우드 아키텍처.
- **외국 법률에 의한 데이터 징발 위험(CLOUD Act & Foreign Jurisdiction Risk)**: 해외 본사를 둔 글로벌 CSP 이용 시 외국 정부의 법적 요구(미국 CLOUD Act 등)로 인해 자국 기업/정부의 기밀 데이터가 강제 열람·압수될 수 있는 안보 위험.

</details>

- 정의/개념: 데이터의 물리적 저장 위치, 운영 권한, 암호화 키를 **자국 법률 관할권 내에 독립적으로 격리하고 통제**하는 주권형 클라우드 아키텍처
- 배경/필요성: 해외 CSP 이용 시 발생하는 **외국 법률(CLOUD Act)에 의한 데이터 강제 징발, 해외 운영자 무단 접근 및 기술 종속 위험** 직면

#### 한줄 요약

- 데이터 거주성, 운영 인력 통제, 외부 암호키 보유를 결합하여 외국의 법적 간섭으로부터 데이터 주권과 디지털 안보를 수호

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **3대 주권 축**: 데이터 주권(Data Sovereignty), 운영 주권(Operational Sovereignty), 기술 주권(Technical Sovereignty).
- **외부 키 관리(External KMS: HYOK)**: 'Hold Your Own Key' 모델로, 암호키를 클라우드 외부의 자체 HSM 장비에 보관하여 CSP가 절대 데이터를 복호화하지 못하도록 차단.

</details>

- 원본 데이터 및 백업의 국외 반출을 엄격히 금지하는 **데이터 거주성(Data Residency)**
- 해외 CSP 본사 엔지니어의 원격 접속을 차단하고 현지 인력만 운영하는 **운영 주권 통제**
- 자체 독립 HSM 장비 기반의 **외부 암호화 키 독점 통제(External KMS / HYOK)**

#### 한줄 요약

- 데이터 위치, 운영자 접근, 암호화 키의 3중 방어벽을 구축하여 완전한 디지털 주권을 달성

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **소버린 클라우드 4대 통제 기둥**: 데이터 거주성(Data Residency), 운영 격리(Local Ops), 키 주권(External KMS), 기술 독립성(Exit Strategy).

</details>

```text
[ 소버린 클라우드(Sovereign Cloud) 3대 주권 방어 아키텍처 ]

 1. [ 데이터 주권 (Data Sovereignty) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • 자국 내 독립 리전 (Local Region) 물리 격리              │
    │  • 데이터/로그/백업의 국외 전송 원천 차단 (Boundary Firewall)│
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 2. [ 운영 주권 (Operational Sovereignty) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • 자국 국적 보안 인가 엔지니어 전담 운영 (Local Staff Only)│
    │  • 글로벌 CSP 본사의 원격 백도어 접근 감사 및 차단         │
    └────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
 3. [ 키 주권 (Key Sovereignty: External KMS / HYOK) ]
    ┌─────────────────────────────────────────────────────────────┐
    │  • On-Premise 자체 HSM 연동 ➔ 고객 승인 없이는 복호화 불가   │
    │  • 오픈소스(K8s, Postgres) 기반 탈출 전략(Exit Strategy)   │
    └─────────────────────────────────────────────────────────────┘
```

선의 의미: 데이터 저장 위치, 운영자 인력 격리, 외부 암호키 제어가 계층적으로 결합되어 주권을 방어하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 거주성 (Residency) | 원본 데이터, 로그, 백업 복제본을 **반드시 국내 지정 데이터센터에 물리적 격리 저장** |
| 운영 주권 (Operational) | 자국 국적의 인가된 인력만 인프라에 접근하며 **글로벌 CSP 직원의 원격 접근 통제** |
| 키 주권 (Key Sovereignty) | 사내 온프레미스 HSM(Hardware Security Module)을 통해 **암호키 생성/폐기 독점 행사** |
| 탈출 전략 (Exit Strategy) | 컨테이너 및 오픈소스 표준을 준수하여 **유사시 타 클라우드로 무손실 즉각 이관 가능성 보장** |

#### 한줄 요약

- 데이터 거주성, 운영 인력 통제, 외부 암호키, 탈출 전략이 결합하여 소버린 클라우드를 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소버린 데이터 복호화 및 접근 5단계 절차**: 접근 요청 $\to$ 운영자 국적/권한 검증 $\to$ 외부 HSM 키 승인 $\to$ 로컬 복호화 $\to$ 감사 증적 기록.

</details>

```text
[ 소버린 클라우드 데이터 복호화 및 접근 제어 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 데이터 조회 및 관리자 접근 요청 접수│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 현지 운영자 신원 및 법적 관할권 검증│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 외부 고객 HSM(External KMS) 키 요청 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 고객 정책 엔진 승인 후 데이터 복호화│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 위변조 불가 감사 로그(Audit) 영구 보관
 └────────────────────────────────────────┘
```

### 동작 원리

1. 접근 요청: 사용자가 자국 내 소버린 리전에 저장된 민감 데이터 조회를 요청.
2. 신원 검증: 로컬 아이덴티티 제공자가 접근자의 국적과 사내 보안 인가 등급을 검증.
3. 키 요청: 복호화를 위해 고객 소유의 온프레미스 외부 KMS(AWS XKS / Google Cloud EKM)로 키 사용 요청을 전달.
4. 승인 및 복호화: 고객 측 정책 엔진이 승인 토큰을 발급한 경우에 한하여 메모리 상에서만 데이터를 복호화.
5. 감사 기록: 복호화 요청자, 사유, 타임스탬프를 블록체인/WORM 스토리지에 위변조 불가 감사 증적으로 기록.

#### 한줄 요약

- 접근 요청 $\to$ 신원 검증 $\to$ 외부 키 요청 $\to$ 정책 승인 복호화 $\to$ 감사 증적 기록의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Data Residency vs Sovereign Cloud**: 단순 물리적 저장소 위치 고정(Residency)과 운영권/암호키까지 관할권 내 통제(Sovereign).

</details>

| 구분 | 단순 데이터 거주성 (Data Residency) | 완전한 소버린 클라우드 (Sovereign Cloud) |
|:---|:---|:---|
| **적용 기준** | 일반 대외 상용 서비스, 단순 위치 규제 준수 환경 | 국가 안보, 국방, 중앙정부 행정망, 핵심 금융 원장 |
| **핵심 특징** | **국내 리전에 데이터 저장, CSP가 암호키 및 운영 총괄** | **국내 저장 + 현지 인력 전담 운영 + 고객 독점 외부 키(HYOK)** |
| **한계** | 외국 정부의 CLOUD Act 징발 요구 시 CSP가 데이터 제출 | 구축 비용 과다 및 글로벌 최신 PaaS 서비스 도입 지연 |

#### 한줄 요약

- 단순 위치 규제는 데이터 거주성, 최고 수준의 국가 안보 및 데이터 주권은 소버린 클라우드를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **AWS XKS (External Key Store)**: AWS 외부의 물리적 HSM 장비와 연동하여 AWS가 암호화 키 원본에 일체 접근하지 못하게 차단하는 솔루션.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CSP 관리형 KMS 사용 시 백도어 및 강제 데이터 징발 위험 | **AWS XKS / Google EKM 기반 온프레미스 Thales HSM 연동** | CSP의 데이터 열람 원천 차단 |
| 특정 CSP 독점 PaaS 종속으로 인한 벤더 락인 및 탈출 불가 | **Kubernetes 및 오픈소스 PostgreSQL 기반 인프라 표준화** | 유사시 즉각적인 타 플랫폼 이관 보장 |
| 전면 소버린 클라우드 구축 시 막대한 인프라 구축 비용 발생 | **데이터 등급제(Data Classification) 수립 후 1급 기밀만 선별 적용** | 주권 보장과 비용 효율성의 최적 절충 |

#### 한줄 요약

- 외부 HSM 연동, 오픈소스 기반 탈출 전략, 데이터 등급별 선별 적용을 통해 소버린 클라우드를 구축

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **국가 디지털 주권 프레임워크(Digital Sovereignty Framework)**: EU의 Gaia-X 및 국내 CSAP 인증 제도와 연계하여 글로벌 클라우드의 기술력과 국가 데이터 주권을 양립시키는 전략.

</details>

- **소버린 클라우드** 기반 지정학적 리스크와 글로벌 데이터 규제에 대응하는 국가적·기업적 필수 안보 인프라 모델이며, 외부 키 관리(HYOK)와 오픈소스 기반 탈출 전략을 결합하여 완벽한 데이터 주권을 확립해야 함

#### 한줄 요약

- 데이터 거주성, 현지 운영권, 외부 암호키 독점을 통해 국가와 기업의 완전한 데이터 주권을 완성
