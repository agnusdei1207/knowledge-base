## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **소버린 클라우드(Sovereign Cloud)**: 특정 관할의 법적 요구, 운영 권한, 데이터•암호키 통제와 기술 자율성을 함께 확보하는 클라우드이다.

</details>

- 정의/개념: 국가•산업 요구에 따라 법적•운영•기술 통제를 확보하는 **소버린 클라우드(Sovereign Cloud)**이다.
- 배경/필요성: 일반 클라우드에서는 외국 관할•특권 접근•공급자 종속에 대한 직접 통제가 제한된다.

#### 한줄 요약

- 자료를 국내에 두는 것에서 끝나지 않고 누가 운영하고 누가 암호키를 승인하며 다른 환경으로 옮길 수 있는지까지 통제하는 모델이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공급망 통제**: 하위 처리자와 기술 구성요소의 관할 위험을 제한하는 통제이다.
- **감사 통제**: 주권 요구 준수 증적을 수집•검증하는 통제이다.
- **출구 통제**: 데이터 반출•복원•폐기 절차를 보장하는 통제이다.
- **저장 위치**: 본 데이터와 복제본이 머무는 관할이다.
- **처리 위치**: 데이터 연산이 실행되는 관할이다.
- **백업 위치**: 백업과 로그 사본이 머무는 관할이다.
- **운영 인력**: 관리 작업을 수행할 수 있는 인력의 관할과 신원이다.
- **특권 접근**: 관리자 권한 사용의 승인•기록 범위이다.
- **암호키 통제**: 복호화 권한과 키 사용 위치를 제한하는 통제이다.

</details>

- **저장 위치**•**처리 위치**•**백업 위치** 기반으로 관할을 통제한다.
- **운영 인력**•**특권 접근**•**암호키 통제** 기반으로 운영을 통제한다.
- **공급망 통제**•**감사 통제**•**출구 통제** 기반 기술 자율성이 핵심이다.

#### 한줄 요약

- 데이터센터가 국내에 있어도 해외 운영자가 암호키를 통제하고 데이터를 이전할 수 있다면 주권 요구가 충족되지 않으므로 데이터 거주지와 운영 통제권을 함께 평가한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **데이터 경계**: 데이터의 저장•처리 위치를 제한하는 경계이다.
- **키 경계**: 암호키의 보관 위치와 사용 승인 권한을 제한하는 경계이다.
- **주권 요구사항**: 법률•데이터 등급•지역•위협에 따라 필요한 격리 수준을 정의한 기준이다.
- **정책 경계**: 허용할 관리 작업과 비상 접근 조건을 제한하는 구성요소이다.
- **신원 경계**: 운영자 신원과 권한의 관할 범위를 제한하는 구성요소이다.
- **관할 내 워크로드**: 승인된 지역과 운영 조건 안에서 데이터 처리를 실행하는 구성요소이다.
- **감사 체계**: 데이터 접근과 특권 작업의 증적을 보존하는 구성요소이다.
- **출구 체계**: 데이터 이전•복원•폐기를 검증하는 구성요소이다.

</details>

```text
주권 통제 구조
      |
      +-- [주권 요구사항]
      |
      +-- [정책•신원 경계]
      |         +-- 운영자 권한•비상 접근
      |
      +-- [데이터•키 경계]
      |         +-- 저장 위치•키 사용 승인
      |
      +-- [관할 내 워크로드]
      |
      +-- [감사•출구 체계]
```

| 구성요소 | 책임 |
|:---|:---|
| 주권 요구사항 | **주권 요구사항**이 법률•지역•격리 수준을 정의 |
| 정책•신원 경계 | **정책 경계**가 관리 작업을, **신원 경계**가 운영자 권한을 통제 |
| 데이터•키 경계 | **데이터 경계**가 저장•처리 위치를, **키 경계**가 키 사용 승인을 통제 |
| 관할 내 워크로드 | **관할 내 워크로드**가 승인 지역•운영 조건에서 실행 |
| 감사•출구 체계 | **감사 체계**가 접근 증적을 보존하고 **출구 체계**가 이전•폐기를 검증 |

#### 한줄 요약

- 주권 요구가 출입 규칙을 정하면 신원 경계와 키 경계가 사람과 데이터의 문을 지키고 감사 체계가 모든 출입과 퇴거를 증명한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **주권 정책 검증**: 관할•대상•목적에 따른 작업 허용 여부를 판정하는 단계이다.
- **고객 키 사용 승인**: 허용 범위에서만 복호화 권한을 부여하는 단계이다.
- **관할 내 작업 실행**: 승인 지역과 격리 조건에서 처리하는 단계이다.
- **접근•처리 증적 기록**: 데이터•특권 작업의 주체와 결과를 보존하는 단계이다.

</details>

```text
데이터 작업 요청
      |
      v
1. 주권 정책 검증
      |
      +-- 정책 위반 --> 작업 차단•거부 기록
      |
      +-- 정책 허용
              |
              v
2. 고객 키 사용 승인
      |
      +-- 승인 거부 --> 복호화 차단•거부 기록
      |
      +-- 승인 완료
              |
              v
3. 관할 내 작업 실행
              |
              v
4. 접근•처리 증적 기록
              |
              v
          결과 반환
```

### 동작 원리

1. **주권 정책 검증**: **주권 정책 검증**으로 관할•대상•목적 조건을 판정한다.
2. **고객 키 사용 승인**: **고객 키 사용 승인**으로 허용 범위의 복호화 권한을 부여한다.
3. **관할 내 작업 실행**: **관할 내 작업 실행**으로 승인 지역•격리 조건을 적용한다.
4. **접근•처리 증적 기록**: **접근•처리 증적 기록**으로 데이터•특권 작업을 보존한다.

#### 한줄 요약

- 관할 운영자가 요청해도 고객 키 정책이 거부하면 복호화할 수 없고 허용된 작업만 국내 워크로드에서 실행되어 감사 기록으로 남는다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 레지던시(Data Residency)**: 데이터의 저장•처리 지역을 지정한 관할 안으로 제한하는 요구이다.

</details>

| 주권 범위 | **데이터 레지던시(Data Residency)** | **소버린 클라우드(Sovereign Cloud)** |
|:---|:---|:---|
| 적용 기준 | 저장•처리 지역 제한 | 법적•운영•기술 통제 |
| 핵심 특징 | 지역 설정•계약 확인 | 인력•키•감사•출구 통제 |
| 한계 | 외국 관할•운영 접근 잔존 | 비용•기능•운영 복잡성 증가 |

#### 한줄 요약

- 데이터 레지던시는 자료의 주소를 고정하고 소버린 클라우드는 주소뿐 아니라 관리자, 열쇠, 이동 수단의 결정 권한까지 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **역외 이전**: 데이터•백업•로그가 허용된 관할 밖으로 이동하는 문제이다.
- **하위 처리자(Subprocessor)**: 클라우드 제공자를 대신해 데이터의 일부를 저장•처리•지원하는 외부 사업자이다.
- **다중 승인**: 특권 접근을 둘 이상의 주체가 허가하는 통제이다.
- **세션 기록**: 전체 관리 작업을 감사 가능하게 기록하는 통제이다.
- **출구 훈련(Exit Exercise)**: 데이터와 워크로드를 개방 형식으로 반출해 다른 환경에서 복원•운영 가능한지 검증하는 활동이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모호한 주권 요구 해석 | 법률•등급•위협별 통제 명세 | 과잉•미달 통제 방지 |
| 백업•로그의 **역외 이전** | 전체 흐름•**하위 처리자(Subprocessor)** 위치 점검 | 숨은 국외 이동 차단 |
| 통제 밖 해외 특권 접근 | 관할 인력•**다중 승인**•**세션 기록** | 관리 접근 통제 |
| 사업자의 키•데이터 동시 접근 | 고객•외부 키와 폐기 검증 | 복호화 결정권 확보 |
| 독점 형식의 이전 실패 | 개방 형식•정기 **출구 훈련(Exit Exercise)** | 공급자 종속 완화 |

#### 한줄 요약

- 본 데이터만 국내에 두지 말고 지원 로그와 백업의 처리 위치까지 추적하고 정기적으로 다른 환경에 복원해 출구 계획의 실행 가능성을 확인해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **관할 위험**: 해당 지역의 법률•접근 권한•이전 제한에서 발생하는 위험이다.

</details>

- 민감 데이터와 높은 **관할 위험**에는 **운영 인력**•**암호키 통제**•**출구 통제** 강화가 핵심이다.

#### 한줄 요약

- 민감도가 높을수록 지역 제한에서 관할 인력, 외부 키 승인, 이전•폐기 검증까지 통제 단계를 높이고 이를 증적으로 확인해야 한다.
