## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **법적·운영·기술 통제 클라우드**: 소버린 클라우드는 특정 관할의 법적 요구와 운영 권한, 기술 자율성을 함께 확보하는 클라우드다.

</details>

- 정의/개념: 국가·산업 요구 기반 **법적·운영·기술 통제 클라우드**
- 배경/필요성: 일반 클라우드에서는 **외국 관할·특권 접근·공급자 종속에 대한 직접 통제가 제한됨**

#### 한줄 요약

- 자료를 국내에 두는 것에서 끝나지 않고 누가 운영하고 누가 암호키를 승인하며 다른 환경으로 옮길 수 있는지까지 통제하는 모델이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공급망·감사·출구 통제**: 공급망, 감사 증적, 출구 절차를 통제해야 기술 자율성과 공급자 변경 가능성을 확보할 수 있다.

</details>

- **저장·처리·백업 위치** 기반 관할 통제
- **운영 인력·특권 접근·키** 기반 운영 통제
- **공급망·감사·출구 통제** 기반 기술 자율성

#### 한줄 요약

- 창고 위치만 국내여도 해외 관리자가 열쇠를 쥐고 자료를 옮길 수 있다면 주권 요구가 충족되지 않으므로 위치와 결정 권한을 함께 본다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **데이터·키 경계**: 데이터·키 경계는 저장 위치와 암호키 사용 승인 권한을 분리하고 통제한다.

</details>

```mermaid
block
    columns 1
    A["주권 요구사항"]
    B["정책·신원 경계"]
    C["데이터·키 경계"]
    D["관할 내 워크로드"]
    E["감사·출구 체계"]
    A --- B
    A --- C
    B --- D
    C --- D
    D --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 주권 요구사항 | 법률·지역·**격리 수준 정의** |
| 정책·신원 경계 | 운영자 권한·**비상 접근 통제** |
| 데이터·키 경계 | 저장 위치·**키 사용 승인 통제** |
| 관할 내 워크로드 | 승인 지역·**운영 조건 실행** |
| 감사·출구 체계 | 접근 증적·**이전·폐기 검증** |

#### 한줄 요약

- 주권 요구가 출입 규칙을 정하면 신원 경계와 키 경계가 사람과 데이터의 문을 지키고 감사 체계가 모든 출입과 퇴거를 증명한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 키 사용 승인 요청**: 데이터 작업 전에 관할, 대상, 목적 조건에 따라 고객 관리 키의 사용 승인을 요청한다.

</details>

```mermaid
sequenceDiagram
    participant U as 사용자·운영자
    participant P as 주권 정책
    participant K as 고객 키 관리
    participant W as 관할 내 워크로드
    participant A as 감사 체계
    U->>P: 데이터 작업 요청
    P->>K: 1. 키 사용 승인 요청
    K-->>P: 2. 암호 연산 승인
    P->>W: 3. 관할 내 작업 명령
    W->>A: 4. 접근·처리 증적 전송
    W-->>U: 처리 결과 반환
```

**동작 원리**

1. **키 사용 승인 요청**: 관할·대상·목적 조건 검증
2. **암호 연산 승인**: 허용 범위의 제한된 키 사용
3. **관할 내 작업 명령**: 승인 지역·격리 조건 적용
4. **접근·처리 증적 전송**: 데이터·특권 작업의 감사 기록

#### 한줄 요약

- 관할 운영자가 요청해도 고객 키 정책이 거부하면 복호화할 수 없고 허용된 작업만 국내 워크로드에서 실행되어 감사 기록으로 남는다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **소버린 클라우드**: 소버린 클라우드는 데이터 위치뿐 아니라 운영 인력, 키, 감사, 이전 권한까지 통제한다.

</details>

| 주권 범위 | 데이터 레지던시 | 소버린 클라우드 |
|:---|:---|:---|
| 적용 기준 | **저장·처리 지역 제한** | **법적·운영·기술 통제** |
| 핵심 특징 | 지역 설정·**계약 확인** | 인력·키·감사·**출구 통제** |
| 한계 | 외국 관할·**운영 접근 잔존** | 비용·기능·**운영 복잡성 증가** |

#### 한줄 요약

- 데이터 레지던시는 자료의 주소를 고정하고 소버린 클라우드는 주소뿐 아니라 관리자, 열쇠, 이동 수단의 결정 권한까지 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **역외 이전**: 역외 이전을 막으려면 본 데이터뿐 아니라 백업, 로그, 하위 처리자의 저장·처리 위치까지 추적해야 한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모호한 **주권 요구 해석** | 법률·등급·위협별 **통제 명세** | 과잉·미달 **통제 방지** |
| 백업·로그의 **역외 이전** | 전체 흐름·**하위 처리자 위치 점검** | 숨은 **국외 이동 차단** |
| 통제 밖 **해외 특권 접근** | 관할 인력·**다중 승인·세션 기록** | **관리 접근 통제** |
| 사업자의 **키·데이터 동시 접근** | 고객·외부 키와 **폐기 검증** | **복호화 결정권** 확보 |
| 독점 형식의 **이전 실패** | 개방 형식·**정기 출구 훈련** | **공급자 종속** 완화 |

#### 한줄 요약

- 본 데이터만 국내에 두지 말고 지원 로그와 백업의 처리 위치까지 추적하고 정기적으로 다른 환경에 복원해 출구 계획의 실행 가능성을 확인해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **데이터 등급·관할 위험**: 데이터 위치, 운영 인력, 키, 출구 통제의 강도는 데이터 등급과 관할 위험을 기준으로 정한다.

</details>

- **데이터 등급·관할 위험**으로 위치·인력·키·출구 통제

#### 한줄 요약

- 민감도가 높을수록 지역 제한에서 관할 인력, 외부 키 승인, 이전·폐기 검증까지 통제 단계를 높이고 이를 증적으로 확인해야 한다.
