## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **멀티 클라우드 전략(Multi-Cloud Strategy)**: 둘 이상의 퍼블릭 클라우드 공급자에 워크로드를 목적별로 분할하거나 중복 배치하는 운영 전략이다.

</details>

- 정의/개념: 복수 공급자에 워크로드를 배치하는 **멀티 클라우드 전략**이다.
- 배경/필요성: 단일 공급자 **장애•종속**으로 서비스 연속성•이전 선택 제약이 발생한다.

#### 한줄 요약

- 가게를 여러 곳 쓰는 것보다 무엇을 나누고 어떻게 바꿔 살지를 정하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공통 운영면**: 여러 공급자의 신원•정책•배포•관측•비용을 일관된 기준으로 관리하는 기반이다.
- **의도적 공급자 배치**: 기능•지역•규제•복구 조건을 근거로 워크로드별 공급자를 선택하는 원칙이다.
- **분할 배치**: 업무를 공급자별 특화 기능에 따라 나누는 방식이다.
- **중복 배치**: 동일 서비스를 여러 공급자에 복제해 장애에 대비하는 방식이다.

</details>

- 기능•지역•규제•복구 조건에 따른 **의도적 공급자 배치**가 핵심이다.
- **분할•중복 배치**로 특화 기능과 공급자 장애 대응을 분리한다.
- 신원•정책•배포•관측•비용의 **공통 운영면** 통합이 핵심이다.

#### 한줄 요약

- 예비 가게가 있어도 재고와 출입증을 맞추고 실제로 손님을 돌려보는 연습이 필요하다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **연결 계층**: 공급자 사이의 요청 라우팅을 관리하는 구성요소이다.
- **데이터 계층**: 공급자 사이의 상태 복제와 전송을 관리하는 구성요소이다.
- **복구 시간 목표(Recovery Time Objective, RTO)**: 장애 뒤 서비스를 복구해야 하는 목표 시간이다.
- **복구 시점 목표(Recovery Point Objective, RPO)**: 장애 시 허용할 최대 데이터 손실 구간이다.
- **코드형 인프라(Infrastructure as Code, IaC)**: 인프라 구성을 선언 코드로 관리하는 방식이다.
- **배포 계층**: 공급자 어댑터로 여러 환경을 생성하는 구성요소이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 서비스 품질의 측정식과 목표값이다.
- **단위 비용**: 요청이나 처리량 한 단위에 드는 비용이다.

</details>

```text
[멀티 클라우드 운영 구조]
          |
          +-- [배치•전환 정책]
          |
          +-- [공통 신원•권한]
          |
          +-- [IaC•배포 계층]
          |
          +-- [연결•데이터 계층]
          |
          +-- [통합 관측•비용]
```

선의 의미: 배치•전환 정책과 공통 신원•권한의 선은 공급자 선택과 조직 역할•권한 매핑의 결합 관계, 공통 신원•권한과 IaC•배포 계층의 선은 허용된 환경 구성 관계, IaC•배포 계층과 연결•데이터 계층의 선은 공급자 간 라우팅•복제 기반 제공 관계, 연결•데이터 계층과 통합 관측•비용의 선은 SLO•단위 비용 수집 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 배치•전환 정책 | 지연•기능•**RTO/RPO**로 공급자 결정 |
| 공통 신원•권한 | 조직 역할과 공급자별 **권한 매핑** |
| IaC•배포 계층 | **IaC 모듈•공급자 어댑터**로 환경 생성 |
| 연결•데이터 계층 | **라우팅•복제•이그레스** 관리 |
| 통합 관측•비용 | 요청 식별자로 **SLO•단위 비용** 연결 |

#### 한줄 요약

- 여러 가게를 쓰되 역할과 전환 방법을 미리 정한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **주 공급자 처리 위치 결정**: 건강•데이터 주권•비용 정책으로 실행 환경을 고르는 단계이다.
- **변경 상태•복제 기준 부여**: 처리 결과에 복제 순서와 재시작 지점을 연결하는 단계이다.
- **RPO 내 예비 상태 검증**: 허용 손실 시점까지 예비 공급자의 동기화를 확인하는 단계이다.
- **공급자 장애 판정**: 오류 지속시간과 건강 상태로 일시 오류와 장애를 구분하는 단계이다.
- **예비 공급자 라우팅 전환**: 데이터 최신성을 확인한 뒤 실행 위치를 바꾸는 단계이다.

</details>

```text
서비스 요청
    |
    v
1. 주 공급자 처리 위치 결정
    |
    v
2. 변경 상태•복제 기준 부여
    |
    v
3. RPO 내 예비 상태 검증
    |
    v
주 공급자 오류 감지
    |
    v
4. 공급자 장애 판정
    |
    +-- 일시 오류 --> 주 환경 재시도
    |
    +-- 공급자 장애 --> 예비 데이터 최신성 충족 여부
                              |
                              +-- 미충족 --> 중단•제한 서비스
                              |
                              +-- 충족 --> 5. 예비 공급자 라우팅 전환
```

**동작 원리**

- **1. 주 공급자 처리 위치 결정**: 건강•주권•비용 정책으로 환경을 선택한다.
- **2. 변경 상태•복제 기준 부여**: 복제 순서와 재시작 지점을 연결한다.
- **3. RPO 내 예비 상태 검증**: 허용 손실 시점까지 동기화를 확인한다.
- **4. 공급자 장애 판정**: 지속시간으로 일시 오류와 장애를 구분한다.
- **5. 예비 공급자 라우팅 전환**: 최신성 확인 후 실행 위치 변경한다.

#### 한줄 요약

- 주 가게가 멈추면 복제된 마지막 재고를 확인한 예비 가게로 손님을 돌린다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **중복 배치**: 같은 서비스와 데이터를 여러 공급자에 준비해 공급자 장애에 대응하는 전략이다.
- **분할 배치**: 업무•계층을 공급자별 특화 기능•지역•격리 요구에 따라 나눠 운영하는 전략이다.

</details>

| 배치 전략 | 분할 배치 | 중복 배치 |
|:---|:---|:---|
| 적용 기준 | **특화 기능•지역•업무 격리** | **공급자 장애 연속성** |
| 핵심 특징 | 업무•계층별 **공급자 역할 분리** | 같은 서비스•데이터의 **공급자 간 복제** |
| 한계 | **교차 의존•비용 경계** 불명확 | **중복 비용•예비 환경 설정 부패** |

#### 한줄 요약

- 분할은 일을 나눠 맡기고 중복은 같은 일을 대신할 준비를 한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **복제 충돌**: 기준 원천 없는 양방향 변경이 서로 다른 값을 만드는 문제이다.
- **이그레스 비용**: 공급자 밖으로 데이터를 전송할 때 드는 비용이다.
- **이식 계층**: 공급자 사이에서 공통화할 구성 범위이다.
- **고유 기능 경계**: 특정 공급자 기능을 직접 사용할 구성 범위이다.
- **전송 예산**: 공급자 간 데이터 이동에 쓸 비용 한도이다.
- **공통 역할**: 조직 전체에서 동일하게 정의한 권한 역할이다.
- **권한 매핑**: 공통 역할을 공급자별 권한 체계에 대응시키는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 목적 없는 공급자 추가로 운영•계약 비용 급증 | 워크로드별 **기능•복원력•종료 조건** 명시 | **공급자 수•운영 비용** 확산 억제 |
| 전면 공통화로 공급자 특화 기능의 이점 상실 | **이식 계층•고유 기능 경계** 분리 | **최저 공통 기능화** 방지 |
| 기준 원천 없이 양방향 복제하면 충돌•전송비 증가 | **기준 원천•RPO•전송 예산** 지정 | **복제 충돌•이그레스 비용** 통제 |
| 공급자별 역할 의미가 달라 과다 권한 발생 | **공통 역할•권한 매핑** 시험 | **권한 의미 불일치** 방지 |
| 문서상 이식성만 믿으면 장애 시 전환 실패 | **장애 전환•복원•종료** 리허설 | **실제 전환 시간•이식성** 검증 |

#### 한줄 요약

- 싼 분석 도구라도 데이터를 옮기는 요금과 시간이 더 크면 분할 이점이 사라진다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **특화 기능**: 특정 공급자에서 얻는 고유 서비스 가치이다.
- **복원력**: 공급자 장애에도 서비스를 유지하는 능력이다.
- **전환 비용**: 다른 환경으로 서비스를 옮기는 데 드는 비용이다.

</details>

- **특화 기능•복원력**이득이 **이그레스•전환 비용** 보다 클 때만 멀티 클라우드 도입이 핵심이다.

#### 한줄 요약

- 가게를 늘려 얻는 기능과 복원력이 재고 동기화•인력•이동 비용보다 커야 한다.
