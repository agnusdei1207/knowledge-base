## 미리 알고가기

- **멀티 클라우드**: 둘 이상의 퍼블릭 클라우드 공급자를 업무별로 병행하는 구성이다
- **분할 배치**: 애플리케이션이나 데이터 처리 단위를 공급자별로 나누는 방식이다
- **중복 배치**: 같은 서비스를 여러 공급자에 두고 장애 전환에 사용하는 방식이다
- **이식성(포터빌리티)**: 실행 패키지·배포 선언·데이터 형식을 다른 환경으로 옮길 수 있는 정도이다
- **이그레스 비용**: 클라우드 외부나 다른 공급자로 데이터를 전송할 때 발생하는 비용이다
- **공통 거버넌스**: 계정·권한·정책·비용·관측 기준을 공급자마다 일관되게 적용하는 체계이다
- **코드형 인프라(Infrastructure as Code, IaC)**: ‘아이에이시’로 읽고 영문 핵심 머리글자를 조합한 표기이며 인프라 구성을 코드로 선언해 반복 생성한다
- **지속적 통합·전달(Continuous Integration/Continuous Delivery, CI/CD)**: ‘시아이 슬래시 시디’로 읽고 두 약어를 빗금으로 이은 표기이며 변경을 자동 검증·전달하는 방식이다
- **공통 신원(Common Identity, Common ID)**: ‘커먼 아이디’로 읽고 Identity를 ID로 줄인 표기이며 사용자 신원·역할을 공급자별 권한에 연결한다
- **컨테이너**: 애플리케이션과 실행 의존성을 묶어 여러 환경에서 같은 방식으로 실행하는 단위이다
- **관리형 서비스**: 공급자가 설치·패치·확장 같은 운영 작업을 대신 수행하는 서비스이다
- **리전·라우팅**: 서비스가 제공되는 지역 단위와 요청을 목적지 경로로 전달하는 규칙이다
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: ‘에이피아이’로 읽고 영문 머리글자를 딴 표기이며 다른 서비스 기능을 호출하는 규약이다

## Ⅰ. 개요

- **정의/개념**: 복수 클라우드에 업무를 **분할·중복 배치**
- **배경/필요성**: 단일 공급자의 **종속·장애 집중 한계** 해소

### 쉽게 이해하기 (학습용)
- 공급자를 쓰는 사실보다 업무 분할과 통제가 핵심이다

## Ⅱ. 특징

- 공급자 강점에 따른 **워크로드 분할**
- 공통 계정·배포·비용의 **통합 거버넌스**
- 컨테이너로 제거할 수 없는 **서비스 차이**

### 쉽게 이해하기 (학습용)
- 장애 분리에는 중복 인프라 비용과 운영 인력이 필요하다

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 역할 |
|:---|:---|
| 배치 정책 | 지연·데이터 위치·관리 서비스·비용으로 공급자를 선택함 |
| 공통 ID·권한 | 조직 계정과 역할을 공급자별 권한 모델에 매핑함 |
| 배포 계층 | 코드화 배포 정책으로 환경별 배포 차이를 통제함 |
| 연결·데이터 계층 | 공급자 간 라우팅과 복제 및 이송 경로를 관리함 |
| 관측·거버넌스·비용 | 공급자 간 요청을 추적하고 비용 위반을 판정함 |

```text
  업무분류
      ↓
  배치선택
      ↓
  연결설계
      ↓
  통제적용
      ↓
  전환검증
```

> 요약: 워크로드는 분산 배치하되 정보는 공통 계층에 모음

### 쉽게 이해하기 (학습용)
- 실행 환경은 달라도 계정과 비용은 한 기준으로 묶음

## Ⅳ. 원리 및 절차 흐름도

```text
업무분류
   ↓
배치선택
   ↓
연결설계
   ↓
통제적용
   ↓
전환검증
```

| 절차 | 설명 |
|:---|:---|
| **업무분류** | 서비스 요구와 데이터 위치를 분류함 |
| **배치선택** | 강점을 비교해 분할 또는 중복을 선택함 |
| **연결설계** | 공급자 간 네트워크와 복제 경로를 설계함 |
| **통제적용** | 계정과 배포 규칙을 공통 기준으로 적용함 |
| **전환검증** | 전환 지연과 데이터 이동 비용을 검증함 |

> 요약: 업무 요구로 공급자를 정하고 통제와 검증을 수행한다

### 쉽게 이해하기 (학습용)
- 공급자를 결정한 뒤 업무 분담과 공통 운영 규칙을 검증한다

## Ⅴ. 종류 및 비교

| 멀티 클라우드 전략 | 분할 배치 | 중복 배치 |
|:---|:---|:---|
| 적용 기준 | 특화 서비스 활용·업무 격리 | 핵심 서비스 연속성 확보 |
| 핵심 특징 | 공급자별 워크로드 분할 | 동일 서비스 복수 공급자 복제 |
| 한계 | 데이터 전송·운영 분산 | 상태 동기화·비용·전환 복잡도 |

> 요약: 분할 전략은 배치 분산이, 중복은 장애 전환이 중심이다

### 쉽게 이해하기 (학습용)
- 분할은 일을 분담하고 중복은 대체 인스턴스를 둠

## Ⅵ. 실무 사례

1. 분석을 **공급자별 분할**, 전송 비용 확인
2. 인증 API를 **중복 배치**, 전환 시간 검증

### 쉽게 이해하기 (학습용)
- 분할 배치는 특화 서비스 효과와 공급자 간 이송 비용을 함께 비교한다
- 중복 배치는 장애 전환 시간과 데이터 동기화 상태를 함께 검증한다

## Ⅶ. 결론

- **분산 효과**가 이동·중복 비용보다 클 때 적용

### 쉽게 이해하기 (학습용)
- 공급자를 늘려 얻는 복원력·기능 효과가 운영 복잡도와 비용을 넘어야 한다
