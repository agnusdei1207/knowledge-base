## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **프로세스**: 운영체제가 주소 공간과 자원을 보호하는 실행 단위이다.
- **스레드**: 프로세스 자원을 공유하는 실행•스케줄링 단위이다.

</details>
- 정의/개념: 프로세스는 독립 주소 공간과 자원을 보호하는 컨테이너이고, 스레드는 그 자원을 공유하며 CPU에 스케줄되는 **실행 단위**이다.
- 배경/필요성: 단일 실행 단위로는 **장애 격리•저비용 상태 공유 동시 충족하기 어렵다**.

#### 한줄 요약

- **장애 격리•상태 공유 빈도**에 따른 실행 단위를 선택한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 공간(Address Space)**: 운영체제가 프로세스별로 격리한 가상 메모리 주소 범위이다.
- **격리 범위**: 프로세스별 주소 공간과 자원을 분리하는 경계이다.
- **공유 범위**: 스레드가 함께 접근하는 주소 공간과 자원의 경계이다.

</details>

- 프로세스의 **독립 주소 공간**으로 장애•권한 격리가 핵심이다.
- 스레드의 **주소 공간 공유**로 상태 교환 비용 절감이 핵심이다.
- **격리•공유 범위**가 전환 비용•오류 전파 범위를 결정한다.

#### 한줄 요약

- **프로세스 격리 비용•스레드 공유 위험** 사이에는 상충 관계가 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **프로세스 제어 블록(Process Control Block, PCB)**: 주소 공간•자원 참조와 프로세스 상태를 저장하는 운영체제 자료구조이다.
- **TCB•실행 문맥(TCB•Execution Context)**: 레지스터•스택•스케줄 상태를 보관하는 스레드별을 구성한다.
- **운영체제 스케줄러(OS Scheduler)**: 다음 실행 스레드를 선택하고 CPU 제어권을 넘기는 구성한다.
- **공유 주소 공간(Shared Address Space)**: 같은 프로세스의 코드•힙•파일 참조를 스레드가 함께 사용하는 영역이다.
- **IPC 채널(IPC Channel)**: 격리된 프로세스 주소 공간 사이에서 데이터를 전달하는 구성한다.

</details>

```text
                 [운영체제 스케줄러]
                          |
┌────────────── 프로세스 경계 ──────────────┐
│ [PCB] -- [공유 주소 공간] -- [TCB•실행 문맥] │
└───┬───────────────────────────────────────┘
    |
[IPC 채널]
```

선의 의미: 스케줄러와 TCB의 선은 실행 대상 선택 관계, 프로세스 경계 안의 선은 PCB•주소 공간•실행 문맥의 결합 관계, PCB와 IPC 채널의 선은 다른 프로세스와 통신하기 위한 외부 연결 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 운영체제 스케줄러 | **스레드 선택•디스패치** |
| PCB | **주소 공간•자원 관리** |
| 공유 주소 공간 | **코드•힙•파일 공유** |
| TCB•실행 문맥 | **독립 실행 상태 보관** |
| IPC 채널 | **프로세스 간 전달** |

#### 한줄 요약

- **프로세스 경계 내 공유•경계 간 IPC** 구조이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **프로그램 카운터(Program Counter, PC)**: 다음에 실행할 명령 주소와 스레드별 중단 위치를 저장하는 레지스터이다.
- **잠금(Lock)**: 공유 상태 접근을 직렬화하는 동기화 수단이다.
- **보호 구간(Critical Section)**: 동시에 실행하면 안 되는 공유 코드 범위이다.
- **직렬화(Serialization)**: 메모리 객체를 프로세스 경계를 넘는 바이트 형식으로 변환하는 처리이다.
- **역직렬화(Deserialization)**: 전달받은 바이트 형식을 프로그램이 사용할 객체로 복원하는 처리이다.

</details>

```text
[작업 간 통신•장애 요구]
           │
           ▼
1. 신뢰•장애 경계 판정
      ┌────┴──────────┐
      │ 경계 분리     │ 상태 공유
      ▼               ▼
   [프로세스]       [스레드]
      │               │
      ▼               ▼
2. IPC 직렬화•전달 3. 공유 상태 소유권 설정
      │               │
      │               ▼
      │          4. 잠금•동기화
      └───────┬───────┘
              ▼
        [작업 결과 반환]
```

**동작 원리**

1. **신뢰•장애 경계 판정**: 오류 전파와 권한 격리 요구를 확인한다.
2. **IPC 직렬화•전달**: 객체를 경계 통과 형식으로 변환•전송한다.
3. **공유 상태 소유권 설정**: 변경 책임과 접근 범위를 지정한다.
4. **잠금•동기화**: 보호 구간의 순서와 값 가시성을 보장한다.

#### 한줄 요약

- **프로세스 IPC•스레드 동기화**의 통신 경로를 구분한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **동기화(Synchronization)**: 여러 스레드의 공유 상태 접근 순서와 값의 가시성을 맞추는 제어한다.

</details>

| 실행 단위 | 프로세스 | 스레드 |
|:---|:---|:---|
| 적용 기준 | 권한•장애•**수명주기 격리** | 빈번한 **상태 공유** |
| 핵심 특징 | 주소 공간 격리•**명시적 IPC** | 주소 공간 공유•**동기화 필요** |
| 한계 | IPC•주소 공간 **전환 비용** | 오류 전파•**동기화 결함** |

> 요약: 프로세스는 주소 공간을 격리하고 스레드는 자원을 공유가 핵심이다.

#### 한줄 요약

- **장애 격리**는 프로세스, 빈번한 상태 공유는 스레드가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **불변성(Immutability)**: 생성 뒤 값을 바꾸지 않아 동시 접근 충돌을 줄이는 성질이다.
- **감독(Supervision)**: 상위 관리자가 하위 프로세스 실패를 감지하는 방식이다.
- **재시작(Restart)**: 실패한 프로세스를 다시 실행하는 복구 방식이다.
- **신뢰 경계(Trust Boundary)**: 서로 다른 권한과 장애 전파 범위를 분리하는 시스템 경계이다.
- **포화 정책(Saturation Policy)**: 요청 큐가 한도에 도달했을 때 작업 거부•대기•호출자 실행 중 하나를 정하는 규칙이다.
- **공유 메모리(Shared Memory)**: 여러 프로세스가 같은 물리 메모리 영역을 매핑해 데이터를 교환하는 IPC 방식이다.
- **소유권(Ownership)**: 공유 상태를 읽거나 변경할 책임을 특정 스레드나 구성요소에 한정하는 설계 원칙이다.
- **스레드 풀(Thread Pool)**: 정해진 수의 스레드를 재사용해 작업을 처리하며 생성•전환 비용을 제한하는 구조이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 여러 스레드가 공유 상태를 갱신해 **경쟁•교착** | **불변성•소유권** 우선 설계와 잠금 순서 고정 | **동시성 결함** 발생률 감소 |
| 스레드 오류가 프로세스 전체로 **장애 전파** | **신뢰 경계**별 프로세스 분리와 감독•재시작 | **장애 격리 범위** 축소 |
| 스레드 수가 늘어 전환•스택 **메모리 급증** | 부하별 **풀 크기•포화 정책** 설정 | **문맥 전환•메모리** 사용량 제한 |
| 잦은 IPC 직렬화•복사로 **처리량 저하** | 메시지 배치와 **공유 메모리** 적용 | **직렬화•복사 비용** 감소 |

#### 한줄 요약

- 브라우저 화면별 **프로세스 격리•감독 재시작**을 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **격리**: 장애 전파를 차단해야 할 때 프로세스를 고르는 기준이다.
- **공유**: 상태 교환이 빈번할 때 스레드를 고르는 기준이다.

</details>

- 격리 요구가 높으면 **프로세스**, 공유 빈도가 높으면 **스레드**를 선택한다.

#### 한줄 요약

- **격리 요구**는 프로세스, 공유 빈도는 스레드를 선택한다.
