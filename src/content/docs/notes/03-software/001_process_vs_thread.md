## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스(Process)**: 독립된 가상 메모리 공간(MMU 페이지 테이블)과 파일 디스크립터를 독점 할당받아 실행되는 OS 자원 격리 단위.
- **스레드(Thread)**: 프로세스 내부의 코드·데이터·힙 메모리를 공유하며 자체 TCB(PC, 스택)만으로 실행되는 CPU 스케줄링 최소 단위.

</details>

- 정의/개념: 독립된 가상 주소 공간을 갖는 **자원 할당 단위(Process)** 와 프로세스 자원을 공유하며 실행되는 **스케줄링 단위(Thread)**
- 배경/필요성: 단일 프로세스 모델로는 **잦은 문맥 전환 오버헤드 극복 및 단일 스레드 장애 전파 방지 불가**

#### 한줄 요약
- 장애 격리가 필요하면 프로세스, 고속 동시 처리가 필요하면 스레드를 선택한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 주소 공간(Virtual Address Space)**: 커널이 프로세스마다 독립 할당하여 타 프로세스의 메모리 무단 접근을 차단하는 보호 경계.
- **문맥 전환 비용(Context Switching Overhead)**: CPU가 프로세스 간 전환 시 레지스터 보존, MMU 페이지 테이블 교체 및 TLB 플러시로 인해 발생하는 지연.

</details>

- 프로세스별 독립 **가상 주소 공간**을 통한 결함 및 보안 격리 경계 제공
- 스레드 간 힙 메모리 공유로 초고속 데이터 교환 및 **문맥 전환 비용** 대폭 절감
- 스레드 공유 메모리 접근 시 데이터 정합성을 위한 뮤텍스/세마포어 **동기화** 필수

#### 한줄 요약
- 프로세스는 결함을 완벽히 격리하고, 스레드는 메모리 공유로 문맥 전환 지연을 최소화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PCB(Process Control Block)**: 프로세스의 가상 주소 공간 기술자, 파일 디스크립터, 스케줄링 상태를 보관하는 커널 자료구조.
- **TCB(Thread Control Block)**: 스레드의 프로그램 카운터(PC), 범용 레지스터, 스택 포인터를 보관하는 경량 커널 자료구조.

</details>

```text
[프로세스 vs 스레드 자원 공유 구조]
|-- 프로세스 A (독립 가상 주소 공간)
|   |-- PCB (페이지 테이블·파일 핸들·스케줄링 상태)
|   |-- 공유 영역 (코드·데이터·힙 메모리)
|   |-- 스레드 1 -> TCB 1 (PC·레지스터·개별 스택)
|   `-- 스레드 2 -> TCB 2 (PC·레지스터·개별 스택)
`-- 프로세스 B (독립 주소 공간 - 프로세스 간 통신은 IPC 경유)
```

선의 의미: 계층 및 메모리 자원 공유 구조

| 구성요소 | 책임 |
|:---|:---|
| **PCB(Process Control Block)** | 가상 주소 공간 기술자, 파일 테이블, 스케줄링 상태 보관 및 결함 격리 |
| 공유 메모리 영역 | 동일 프로세스 내 스레드들이 공유하는 Code, Data, **Heap** 세그먼트 |
| **TCB(Thread Control Block)** | 스레드별 프로그램 카운터(PC), CPU 레지스터 세트, 독립 **스택** 영역 관리 |
| IPC 채널 | 서로 다른 프로세스 간 안전한 데이터 교환을 위한 파이프, 소켓, 공유 메모리 통로 |

#### 한줄 요약
- 프로세스는 독립된 PCB와 주소 공간을 가지며, 스레드는 프로세스 힙을 공유하며 자체 TCB로 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 다중 스레드가 동시에 공유 자원에 접근하면 데이터 경쟁이 발생하는 코드 구간.

</details>

```text
작업 분배 및 동시성 처리 요청
        │
   작업 간 완벽한 장애 격리 및 보안 분리가 필요한가?
   ┌────┴─────┐
  예           아니오 (고속 데이터 공유 우선)
   │             │
프로세스 분리     스레드 분기 (Thread Fork)
   │             │
IPC 직렬화 및    공유 힙 메모리 접근
페이지 테이블 교체 │
   │        임계 구역(Critical Section) 뮤텍스 동기화 수행
   │             │
   └────┬────────┘
        │
   작업 완료 및 결과 반환
```

#### 한줄 요약
- 격리 요구 시 프로세스 분리(IPC), 고속 처리 시 스레드 분기(동기화)로 처리 경로가 갈린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 테이블 교체(Page Table Switch)**: 프로세스 전환 시 CPU CR3 레지스터를 변경하여 TLB 캐시가 무효화되는 고비용 동작.

</details>

| 실행 단위 | 프로세스 (Process) | 스레드 (Thread) | 가상 스레드 (Virtual Thread) |
|:---|:---|:---|:---|
| 적용 기준 | 결함 격리 및 보안 경계 필수 작업 | 고빈도 I/O 및 연산 병렬화 작업 | 수백만 개 동시 연결 I/O 서버 |
| 핵심 특징 | 독립 가상 메모리, **PCB** 기반 격리 | 메모리(Heap) 공유, **TCB** 경량 제어 | JVM 사용자 공간 스케줄링, 극소 메모리 |
| 한계점 | **페이지 테이블 교체** 및 IPC 오버헤드 | 단일 스레드 장애 시 프로세스 전체 크래시 | CPU 바운드 연산 시 스루풋 향상 없음 |

#### 한줄 요약
- 결함 격리는 프로세스, 고속 멀티태스킹은 스레드, 대규모 동시 I/O는 가상 스레드를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 스레드를 미리 생성하여 큐에 대기시킴으로써 생성/소멸 오버헤드를 제거하고 최대 동시 실행 수를 제한하는 패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드 공유 자원 동시 접근 시 데이터 레이스 | 상호 배제 뮤텍스 및 락프리(Lock-Free) 원자 연산 적용 | 데이터 무결성 보장 및 락 경합 병목 완화 |
| 특정 스레드의 세그멘테이션 폴트로 전체 프로세스 다운 | 보안/결함 민감 구간을 별도 **워커 프로세스**로 분리 | 장애 영향도를 해당 프로세스로 국소화 |
| 요청마다 스레드 생성 시 스택 메모리 고갈(OOM) | **스레드 풀(Thread Pool)** 및 워커 큐 도입 | 스레드 생성 지연 제거 및 메모리 사용량 상한 통제 |
| 멀티프로세스 환경에서 IPC 직렬화 병목 | POSIX 공유 메모리(Shared Memory) 및 세마포어 적용 | 메모리 복사 오버헤드 제거 및 통신 지연 최소화 |

#### 한줄 요약
- 락프리 동기화, 워커 프로세스 격리, 스레드 풀링, 공유 메모리 IPC로 시스템 안정성을 극대화한다.

## Ⅶ. 결론

- 장애 격리가 중요한 보안·안전 모듈은 **멀티프로세스**, 고속 트랜잭션 처리는 **스레드 풀 기반 멀티스레딩**을 채택하여 신뢰성과 성능 최적화 달성

#### 한줄 요약
- 격리성과 성능 요구조건에 따라 프로세스와 스레드를 적절히 혼용하는 아키텍처 설계가 필수적이다.
