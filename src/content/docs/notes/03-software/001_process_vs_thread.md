## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **프로세스(Process)**: 운영체제가 독립된 주소 공간과 자원을 부여하고 보호하는 실행 단위임.
- **스레드(Thread)**: 동일 프로세스 내 주소 공간 및 자원을 공유하는 CPU 스케줄링의 기본 단위.

</details>

- 정의/개념: **프로세스**의 독립 주소 공간 및 자원 보호 컨테이너 역할과 **스레드**의 자원 공유 기반 CPU 스케줄링 실행 단위 제공
- 배경/필요성: 단일 실행 단위 한계 극복을 위한 장애 격리와 저비용 상태 공유 간 상충 관계 해결 필요성

#### 한줄 요약

- 장애 격리와 상태 공유 빈도에 따라 **프로세스** 또는 **스레드**를 선택한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 공간(Address Space)**: 운영체지가 프로세스별로 독립 할당하여 격리한 가상 메모리 주소 범위.
- **격리 범위(Isolation Boundary)**: 프로세스 간 주소 공간 및 시스템 자원을 안전하게 분리하는 경계.
- **공유 범위(Shared Boundary)**: 동일 프로세스 내부 스레드가 함께 접근 가능한 메모리 및 자원 영역.

</details>

- 프로세스별 **주소 공간** 독점을 통한 장애 및 권한 격리 수행
- 스레드 **공유 범위** 확장에 따른 상태 교환 비용 절감 및 오류 전파 위험의 트레이드오프 존재
- **격리 범위**와 **공유 범위** 설정에 의한 문맥 전환 비용 및 장애 영향도 결정

#### 한줄 요약

- 프로세스 격리 비용과 스레드 공유 위험 사이에는 상충 관계가 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **프로세스 제어 블록(Process Control Block, PCB)**: 주소 공간•자원 참조와 프로세스 상태를 저장하는 운영체제 커널의 핵심 자료구조.
- **TCB•실행 문맥(Thread Control Block & Execution Context)**: 레지스터, 스택, 스케줄링 상태를 보관하는 스레드별 개별 구조.
- **운영체제 스케줄러(OS Scheduler)**: 다음 실행 대상을 선점/비선점하여 CPU 제어권을 할당하는 제어 주체.
- **공유 주소 공간(Shared Address Space)**: 동일 프로세스 내 코드, 데이터, 힙 및 파일 디스크립터를 공유하는 영역.
- **IPC 채널(Inter-Process Communication Channel)**: 격리된 프로세스 주소 공간 간 데이터 전송 및 메시지 교환 통로.

</details>

```text
                 [운영체제 스케줄러]
                          |
┌────────────── 프로세스 경계 ──────────────┐
│ [PCB] -- [공유 주소 공간] -- [TCB•실행 문맥] │
└───┬───────────────────────────────────────┘
    |
[IPC 채널]
```

- 선의 의미: 스케줄러와 TCB의 실행 대상 선택 관계, PCB•주소 공간•실행 문맥의 결합 관계, PCB와 IPC 채널의 외부 통신 연결 관계를 시각화

| 구성요소 | 책임 |
|:---|:---|
| 운영체제 스케줄러 | 스레드 선택•디스패치 |
| PCB | 주소 공간•자원 관리 |
| 공유 주소 공간 | 코드•힙•파일 공유 |
| TCB•실행 문맥 | 독립 실행 상태 보관 |
| IPC 채널 | 프로세스 간 전달 |

#### 한줄 요약

- **공유 주소 공간**과 **IPC 채널**로 경계 내부 공유와 경계 간 통신을 구분한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **프로그램 카운터(Program Counter, PC)**: 다음 실행 명령 주소와 스레드별 중단 지점을 저장하는 레지스터.
- **잠금(Lock)**: 공유 상태 동시 접근을 직렬화하여 데이터 경합을 방지하는 동기화 메커니즘.
- **보호 구간(Critical Section)**: 공유 자원에 접근하여 상호 배제가 보장되어야 하는 코드 영역.
- **직렬화(Serialization)**: 메모리 객체를 메모리/네트워크 경계를 넘는 바이트 스트림으로 변환하는 처리.
- **역직렬화(Deserialization)**: 전송받은 바이트 스트림을 메모리 상의 객체 구조로 복원하는 처리.
- **신뢰·장애 경계 판정(Trust & Fault Boundary Judgment)**: 오류 전파 차단과 권한 격리 요구사항에 기초한 경계 결정 단계.
- **IPC 직렬화·전달(IPC Serialization & Transfer)**: 객체를 바이트 Stream 형태로 직렬화하여 프로세스 경계로 전송하는 단계.
- **공유 상태 소유권 설정(Shared State Ownership Setting)**: 공유 자원의 변이 권한 및 접근 책임을 특정 구성요소에 부여하는 단계.
- **잠금·동기화(Locking & Synchronization)**: Critical Section 순서 제어 및 메모리 가시성을 확보하는 단계.

</details>

```text
[작업 간 통신•장애 요구]
           │
           ▼
1. 신뢰•장애 경계 판정
      ┌────┴──────────┐
      │ 경계 분리     │ 상태 공유
      ▼               ▼
   [프로세스]       [스레드]
      │               │
      ▼               ▼
2. IPC 직렬화•전달 3. 공유 상태 소유권 설정
      │               │
      │               ▼
      │          4. 잠금•동기화
      └───────┬───────┘
              ▼
        [작업 결과 반환]
```

### 동작 원리

1. **신뢰•장애 경계 판정**: 오류 전파 차단 및 권한 격리 요구 사항 검증
2. **IPC 직렬화•전달**: 객체 데이터의 경계 통과용 바이트 스트림 변환 및 이송
3. **공유 상태 소유권 설정**: 상태 변경 책임 명확화 및 접근 동기화 범위 지정
4. **잠금•동기화**: Critical Section 순서 제어 및 메모리 가시성 확보

#### 한줄 요약

- 프로세스는 **IPC 직렬화·전달**, 스레드는 **공유 상태 소유권 설정**과 **잠금·동기화**를 사용한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **동기화(Synchronization)**: multi-thread 환경에서 공유 자원 접근 순서와 값의 메모리 가시성을 통제하는 제어 기술.

</details>

| 실행 단위 | 프로세스 | 스레드 |
|:---|:---|:---|
| 적용 기준 | 권한•장애•수명주기 격리 | 빈번한 상태 공유 |
| 핵심 특징 | 주소 공간 격리•명시적 IPC | 주소 공간 공유•**동기화** 필요 |
| 한계 | IPC•주소 공간 전환 비용 | 오류 전파•동기화 결함 |

> 요약: 프로세스의 주소 공간 격리와 스레드의 자원 공유 구조 비교

#### 한줄 요약

- 장애 격리는 프로세스, 빈번한 상태 공유는 스레드가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **불변성(Immutability)**: 객체 생성 후 상태 변이를 불허하여 동시성 경합을 원천 예방하는 특성.
- **감독(Supervision)**: 상위 프로세스가 하위 노드의 비정상 종료를 관제 및 제어하는 메커니즘.
- **재시작(Restart)**: 장애가 발생한 프로세스를 재할당 및 실행하여 서비스를 복구하는 패턴.
- **신뢰 경계(Trust Boundary)**: 보안 권한 레벨 및 장애 전파 방지 영역을 구분하는 시스템 경계.
- **포화 정책(Saturation Policy)**: 작업 큐 가득 참 시 Abort, Discard, Caller-Runs 등 처리 방식을 선택하는 규칙.
- **공유 메모리(Shared Memory)**: 동일 물리 메모리 영역을 매핑하여 최속 데이터 교환을 구현하는 IPC 기법.
- **소유권(Ownership)**: 특정 스레드에 상태 변이 권한을 단일 부여하여 경합을 차단하는 아키텍처 원칙.
- **스레드 풀(Thread Pool)**: 미리 생성된 스레드를 재사용하여 오버헤드와 자원 낭비를 억제하는 관리 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 여러 스레드가 공유 상태를 갱신해 경쟁•교착 | **불변성**과 **소유권** 우선 설계 및 잠금 순서 고정 | 동시성 결함 발생률 감소 |
| 스레드 오류가 프로세스 전체로 장애 전파 | **신뢰 경계**별 프로세스 분리와 **감독**•**재시작** | 장애 격리 범위 축소 |
| 스레드 수가 늘어 전환•스택 메모리 급증 | **스레드 풀** 크기와 **포화 정책** 설정 | 문맥 전환•메모리 사용량 제한 |
| 잦은 IPC 직렬화•복사로 처리량 저하 | 메시지 배치와 **공유 메모리** 적용 | 직렬화•복사 비용 감소 |

#### 한줄 요약

- 웹 브라우저 탭(Tab)별 Multi-process Architecture 적용 및 Watchdog 기반 프로세스 Supervisor/재시작 패턴을 도입하여 Fault Isolation을 보장한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **실행 단위 선택 기준(Execution Unit Selection Criteria)**: 격리 레벨 및 상태 공유 빈도 요구사항을 종합 평가하는 판단 기준.

</details>

- **실행 단위 선택 기준**에 따른 high-isolation 요구 시 **프로세스**, high-frequency state sharing 시 **스레드** 모델 채택

#### 한줄 요약

- Fault Tolerance & Privilege Boundary에는 Process isolation, Intra-process Parallelism & In-Memory State Exchange에는 Thread concurrency 모델을 적용한다.
