## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스(Process)**: 독립된 가상 주소 공간을 할당받아 실행되는 프로그램 인스턴스로, 한 프로세스의 오류가 다른 프로세스에 전파되지 않도록 메모리 보호 경계를 형성하는 실행 단위.
- **스레드(Thread)**: 프로세스 내부에서 코드·데이터·힙을 공유하며 독립 스케줄링되는 경량 실행 흐름으로, 자체 스택과 레지스터 상태만 개별 보유하는 실행 단위.
- **IPC(Inter-Process Communication)**: 독립 주소 공간을 가진 프로세스 간 데이터를 교환하기 위해 커널이 제공하는 파이프·소켓·공유 메모리 등의 통신 기법.
- **동기화(Synchronization)**: 여러 스레드가 공유 자원에 동시 접근할 때 데이터 일관성을 보장하기 위해 뮤텍스·세마포어로 접근 순서를 제어하는 기법.

</details>

- 정의/개념: 독립 **주소 공간** 기반 자원 격리 단위 **프로세스**와, 프로세스 내부 자원을 공유하는 경량 실행 단위 **스레드** 비교
- 배경/필요성: 단일 흐름의 동시 처리 한계를 경량 스레드로 해소하되, 장애 전파 차단에는 프로세스 격리 필요

#### 한줄 요약

- 장애 격리가 필요하면 프로세스, 빠른 동시 처리가 필요하면 같은 프로세스 내 스레드를 선택하는 실행 단위 판단 기준

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 주소 공간(Virtual Address Space)**: 커널이 프로세스마다 독립적으로 할당하는 가상 메모리 영역으로, 다른 프로세스의 메모리에 직접 접근할 수 없는 보호 경계를 형성.
- **격리 경계(Isolation Boundary)**: 한 프로세스의 비정상 종료·메모리 오염이 다른 프로세스에 전파되지 않도록 운영체제가 보장하는 보호 경계.
- **문맥 전환 비용(Context Switching Overhead)**: CPU가 현재 실행 중인 프로세스(또는 스레드)를 멈추고 다른 것으로 전환할 때 레지스터 저장·복원, 페이지 테이블 교체 등에 소요되는 지연.

</details>

- 프로세스별 독립 **가상 주소 공간** 기반 결함·보안 **격리 경계** 분리
- 스레드 간 메모리 공유로 **IPC** 통신 비용 절감, **동기화** 의무 수반
- 주소 공간 전환 유무에 따른 프로세스 전환의 높은 **문맥 전환 비용**

#### 한줄 요약

- 프로세스는 주소 공간 분리로 장애를 격리하지만 전환 비용이 크고, 스레드는 메모리를 공유해 빠르지만 동기화 없이는 데이터 일관성 미보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PCB(Process Control Block)**: 프로세스의 가상 주소 공간 기술자·파일 핸들·스케줄링 상태를 보관하는 커널 자료 구조.
- **TCB(Thread Control Block)**: 스레드의 프로그램 카운터·레지스터·스택 포인터를 보관하는 경량 커널 자료 구조.

</details>

```text
[ 프로세스·스레드 자원 구조 ]
프로세스 A
├─ PCB (가상 주소 공간·파일 핸들·스케줄링 상태)
├─ 공유 영역 (코드·데이터·힙)
│   ├─ 스레드 T1 ─ TCB (PC·레지스터·스택)
│   └─ 스레드 T2 ─ TCB (PC·레지스터·스택)
└─ IPC 채널 (파이프·소켓·공유 메모리)
프로세스 B
└─ PCB (독립 주소 공간)
```

선의 의미: 가지(`├─`, `└─`)는 프로세스 내 소유 관계, 가로선은 프로세스 간 IPC 통신 경로

| 구성요소 | 책임 |
|:---|:---|
| PCB | **가상 주소 공간**·파일·스케줄링 상태 보관 및 격리 경계 형성 |
| 공유 영역 | 동일 프로세스의 스레드 간 코드·데이터·**힙** 공유 공간 제공 |
| TCB | 스레드별 **PC·레지스터·스택** 독립 보관 |
| IPC 채널 | 프로세스 간 데이터 교환을 위한 **IPC** 통로 제공 |

#### 한줄 요약

- 무거운 PCB 안에 경량 TCB들이 메모리를 공유하고, 프로세스 간은 IPC 통로로만 통신

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 여러 스레드가 동시에 접근하면 데이터 불일관이 발생하는 코드 블록으로, 뮤텍스 등으로 상호 배제를 강제해야 하는 구간.
- **직렬화(Serialization)**: 메모리의 복잡한 자료구조를 IPC 채널로 전송 가능한 1차원 바이트 스트림으로 변환하는 작업.

</details>

```text
작업 분배 요청
   │
   ▼
1. 격리 수준 판정 (장애 전파 허용 여부)
├─ 격리 필요: 프로세스 분리
│   └─ 2. IPC 직렬화·전달 (파이프·소켓)
│         └─ 프로세스 문맥 전환
└─ 공유 허용: 스레드 분기
    └─ 3. 임계 구역 동기화 (Mutex·Semaphore)
          └─ 작업 결과 반환
```

**동작 원리**

1. **격리 수준 판정**: 장애 전파 차단이 필요하면 프로세스, 고속 공유 처리가 필요하면 스레드 선택
2. **IPC 직렬화·전달**: 프로세스 경로에서는 데이터를 직렬화해 파이프·소켓으로 전달 후 문맥 전환 수행
3. **임계 구역 동기화**: 스레드 경로에서는 공유 메모리 접근 시 **임계 구역**을 뮤텍스·세마포어로 상호 배제

#### 한줄 요약

- 격리 수준에 따라 IPC 경로(프로세스)와 동기화 경로(스레드)로 분기

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 테이블 교체(Page Table Switch)**: 프로세스 문맥 전환 시 CPU의 주소 변환 테이블을 새 프로세스 것으로 교체하는 고비용 연산.

</details>

| 비교 항목 | 프로세스 (Process) | 스레드 (Thread) |
|:---|:---|:---|
| 적용 기준 | 장애 격리·보안 경계 분리가 필수인 작업 | 고빈도 동시 처리로 **문맥 전환 비용** 최소화 필요 시 |
| 핵심 특징 | 독립 **가상 주소 공간**으로 메모리 **격리 경계** 형성 | 코드·데이터·힙 공유, **TCB**만 개별 보유 |
| 한계 및 위험 | **IPC** 오버헤드 및 **페이지 테이블 교체** 비용 증가 | 한 스레드 오류 시 동일 프로세스 내 전체 스레드 영향 |

#### 한줄 요약

- 장애를 막아야 하면 무거운 프로세스, 빠른 처리가 필요하면 경량 스레드를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 스레드를 사전에 일정 수 생성·대기시켜 요청마다 신규 생성 비용을 제거하고 동시 실행 수를 제한하는 기법.
- **교착 상태(Deadlock)**: 두 스레드가 서로 상대방이 보유한 잠금을 기다리다가 영구히 진행되지 못하는 순환 대기 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드 간 공유 자원의 순환 대기로 **교착 상태** 발생 | 불변 객체 우선·잠금 순서 전역 통일 적용 | 순환 대기 차단으로 **교착 상태** 예방 |
| 스레드 오류가 전체 프로세스를 중단시키는 전파 장애 | 격리 필요 구간을 별도 **프로세스**로 분리 | 장애 범위를 단일 프로세스 내로 봉쇄 |
| 요청마다 스레드 생성으로 메모리·생성 오버헤드 급증 | **스레드 풀**로 최대 동시 스레드 수 제한 및 대기 큐 운영 | 생성 비용 제거 및 **OOM(Out of Memory)** 방지 |

#### 한줄 요약

- 장애 전파 위험 구간은 프로세스로 분리하고, 고빈도 단기 작업은 스레드 풀로 생성 비용을 줄임

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실행 단위 선택 기준**: 장애 격리 필요성(프로세스)과 동시 처리 효율(스레드) 중 우선 요구로 실행 단위를 결정하는 판단 기준.

</details>

- **격리 경계** 필요 시 **프로세스**, **문맥 전환 비용** 최소화 필요 시 **스레드 풀** 기반 스레드 선택

#### 한줄 요약

- 장애 격리가 우선이면 프로세스, 처리 효율이 우선이면 스레드 풀 기반 스레드를 선택
