## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스(Process)**: 프로그램이 메모리에 올라가서 실행 중인 상태로, 남의 영역을 침범하지 못하게 철통 방어막(가상 주소 공간)을 두른 독립적인 작업 덩어리이다.
- **스레드(Thread)**: 프로세스라는 울타리 안에서 메모리를 공평하게 나눠 쓰며, 굳이 방어막을 치지 않고 가볍고 빠르게 움직이는 실질적인 일꾼(실행 흐름)이다.
- **공유 메모리(Shared Memory)**: 프로세스끼리 원래는 남남이지만, "여기 창고는 같이 쓰자" 하고 특정 메모리 구역을 열어둬서 빛의 속도로 데이터를 주고받는 꼼수이다.
- **동기화(Synchronization)**: 여러 스레드가 동시에 같은 데이터를 물어뜯으려 할 때, "너 먼저 쓰고 다음 너!" 하고 순서를 멱살 잡고 정해주는 질서 유지 기법이다.

</details>

- 정의: 독립된 가상 주소 공간을 할당받아 장애를 격리하는 **프로세스**와, 그 내부에서 자원을 공유하며 실행되는 경량 CPU 스케줄링 단위인 **스레드** 비교
- 배경: 단일 실행 흐름으로는 동시 처리량 확보에 한계가 있어 가벼운 일꾼(스레드)이 필요하지만, 동시에 메모리가 꼬이는 장애를 막기 위한 격리(프로세스)도 필요하기 때문

#### 한줄 요약

- 죽어도 혼자 죽는 튼튼한 놈(프로세스)을 쓸 건지, 방어막 없이 가볍게 같이 일하는 놈(스레드)을 쓸 건지 결정하는 기준이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간(Virtual Address Space)**: 프로세스마다 "여긴 내 땅이야!" 하고 커널이 선을 그어준 전용 메모리 구역으로, 다른 프로세스가 함부로 못 넘어오는 철통 방어선이다.
- **격리 범위(Isolation Boundary)**: 한 프로세스가 에러를 뿜으며 폭발해도 옆 프로세스는 털끝 하나 안 다치게 막아주는 방화벽 같은 경계선이다.
- **공유 범위(Shared Boundary)**: 한 프로세스 안에 있는 스레드들이 코드나 데이터를 "이건 우리끼리 같이 쓰자" 하고 열어둔 공용 구역이다.
- **문맥 전환 비용(Context Switching Overhead)**: CPU가 1번 일꾼 하다가 2번 일꾼으로 갈아탈 때, 머릿속을 싹 비우고 새 작업 파일을 꺼내느라 버벅거리는 딜레이(지연)이다.

</details>

- 프로세스별 **가상 주소 공간**으로 결함과 보안 경계를 엄격하게 분리함.
- 스레드의 메모리 공유로 통신 비용은 줄지만 데이터가 꼬이지 않게 **동기화**가 강제됨.
- 주소 공간 전환 유무에 따라 스레드 간 전환보다 프로세스 간 전환의 **문맥 전환 비용**이 압도적으로 높음.

#### 한줄 요약

- 프로세스는 안전하지만 무겁고, 스레드는 가볍고 빠르지만 동기화를 안 해주면 서로 데이터를 박살 낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PCB(Process Control Block)**: 프로세스의 주민등록증 같은 놈으로, "얘는 누구고 메모리는 어딨고 상태는 어떤지" 커널이 꼼꼼히 적어둔 무거운 장부이다.
- **TCB(Thread Control Block)**: 스레드의 사원증 같은 놈으로, "얘가 지금 어느 코드를 실행 중이고 스택은 어딨는지" 짧게 메모해 둔 가벼운 장부이다.
- **IPC(Inter-Process Communication)**: 철통 방어된 프로세스끼리 말 섞을 일이 있을 때, 커널 몰래 파이프나 소켓을 뚫어서 데이터를 주고받는 밀거래 통로이다.

</details>

```text
[ 프로세스 및 스레드 십자포화 아키텍처 프레임워크 ]
                   [ 운영체제 스케줄러 (작업 반장) ]
                             │
 ┌────────────── [ 프로세스 경계 (철통 방어막) ] ──────────────┐
 │ [ PCB (주민등록증) ] ── [ 공유 주소 공간 ] ── [ TCB (사원증) ] │
 └─────────────┬─────────────────────────────────────────────┘
               │
   [ IPC 채널 (파이프/소켓 밀거래) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 운영체제 스케줄러 | **TCB**와 **PCB**를 보고 "다음엔 네가 CPU 써라" 하고 시간을 쪼개주는 악덕 작업 반장 |
| **PCB** (Process Control Block) | 가상 **주소 공간**을 관리하고, 에러가 나면 프로세스 단위로 싹둑 잘라내는 격리 장부 |
| 공유 주소 공간 | 프로세스 안에서 스레드들이 옹기종기 모여 쓰는 코드, 데이터, 힙(Heap) 공용 구역 |
| **TCB** (Thread Control Block) | 각 스레드가 자기가 어디까지 일했는지(PC, 레지스터) 짧게 기억해 두는 사원증 |
| **IPC** 채널 | 꽉 막힌 프로세스들 사이에 파이프나 소켓을 뚫어 데이터를 주고받게 만드는 통로 |

#### 한줄 요약

- 무거운 장부(PCB) 안에 가벼운 사원증(TCB)들이 모여서 메모리를 같이 쓰고, 밖이랑은 IPC 통로로만 대화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보호 구간(Critical Section)**: 여러 스레드가 동시에 건드리면 데이터가 박살 나는 위험 구역으로, 무조건 한 놈씩만 들어가게 자물쇠를 채워야 하는 코드 블록이다.
- **직렬화(Serialization)**: 프로세스끼리 통신(IPC)할 때 메모리에 퍼져 있는 복잡한 데이터를, 한 줄짜리 데이터 끈으로 쫙 묶어서 전송하기 좋게 만드는 압축 작업이다.

</details>

```text
[ 작업 간 통신 및 동기화 분기 흐름 ]
                                 │
                                 ▼
   [ 1. 신뢰 경계 판정: 같이 죽어도 되면 스레드, 혼자 살아야 하면 프로세스로 분기 ]
                                 │
                 ┌───────────────┴───────────────┐
            ( 철통 방어 프로세스 )             ( 공유 상태 스레드 )
                 ▼                               ▼
 [ 2. IPC 직렬화: 데이터를 파이프로 보냄 ]  [ 3. 공유 상태 소유권 설정: 같이 씀 ]
                 │                               │
                 ▼                               ▼
 [ 4. 프로세스 컨텍스트 스위치 발생 ]        [ 5. 보호 구간(자물쇠) 멱살 동기화 ]
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
                         [ 작업 결과 반환 ]
```

### 동작 원리

1. 신뢰·장애 경계 판정: 작업 간 보안/오류 격리 수준에 따라 프로세스로 분리할지, 스레드 멀티태스킹으로 갈지 결정함.
2. IPC 직렬화·전달: 프로세스를 고르면 데이터를 **직렬화**해서 파이프나 소켓 같은 **IPC** 통로로 쑤셔 넣음.
3. 공유 상태 소유권 설정: 스레드를 고르면 귀찮은 통신 없이 힙(Heap) 메모리를 냅다 같이 쓰기로 합의함.
4. 잠금·동기화: 스레드가 **보호 구간**에 들어갈 때 데이터가 안 박살나게 자물쇠(Mutex)를 걸고 동기화함.

#### 한줄 요약

- 서로 남남이면 무거운 통로(IPC)를 뚫고, 식구면 메모리를 같이 쓰되 싸우지 않게 자물쇠(동기화)를 채워라.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Context Switch Overhead**: CPU가 다른 프로세스로 갈아탈 때, 기존에 띄워둔 메모리 지도(페이지 테이블)를 다 찢어버리고 새로 그려야 해서 생기는 끔찍한 시간 낭비이다.

</details>

| 비교 항목 | **프로세스** (Process) | **스레드** (Thread) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 크롬 브라우저 탭처럼 하나가 폭발해도 옆 탭이 안 죽게 멱살 잡고 버텨야 할 시 | 웹 서버처럼 수천 명의 요청을 미친 듯이 가볍고 빠르게 쳐내야 할 시 |
| 메모리 구성 | 독립된 가상 **주소 공간**을 혼자 독식하며, 남이 절대 건드리지 못하게 방어함 | 힙, 데이터는 다 같이 노나 쓰고 꼴랑 스택(Stack) 하나만 자기 걸로 챙김 |
| 극복해야 할 태생적 한계점 | 통신 한 번 하려면 **IPC**를 뚫어야 하고, 전환할 때마다 오버헤드가 무식하게 큼 | 하나가 맛가서 메모리를 헤집어놓으면 안방에 있던 스레드 전체가 동반 자살함 |

#### 한줄 요약

- 하나 죽어도 버티려면 무거운 프로세스를 쓰고, 다 같이 빠릿하게 일하되 동반 자살 리스크를 안으려면 스레드를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 일꾼(스레드)이 필요할 때마다 뽑고 자르면 비용이 더 드니까, 미리 10명 뽑아서 대기실에 묶어놓고 필요할 때 빼다 쓰는 인력 사무소이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드들이 같은 데이터를 서로 물어뜯다가 다 같이 영원히 멈추는 데드락 참사 발발 | 불변 객체를 떡칠하고, 자물쇠 잠그는 순서를 멱살 잡고 통제함 | 데이터 경합과 순환 대기로 인한 시스템 정지 완벽 억제 |
| 스레드 하나가 메모리를 꼬아버려서 프로세스 전체가 동반 자살하는 대형 사고 | 절대로 죽으면 안 되는 코어 작업은 **신뢰 경계**를 갈라 프로세스로 아예 찢어버림 | 장애가 옆 동네로 번지는 걸 막고 튼튼한 생존력 사수 |
| 사용자 들어올 때마다 스레드를 무식하게 찍어내다가 메모리 터져서 서버 뻗음 | 미리 일정 개수만 만들어놓는 **스레드 풀(Thread Pool)**로 묶고 큐에 줄 세움 | 무한 생성으로 인한 오버헤드와 OOM(Out of Memory) 재앙 컷 |

#### 한줄 요약

- 동반 자살 리스크는 프로세스로 찢어 막고, 잦은 생성 비용은 스레드 풀(인력 사무소)로 때워라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실행 단위 선택 기준(Execution Unit Selection Criteria)**: 이 작업이 죽으면 안 되는 곳인지(프로세스), 아니면 빠릿하게 메모리를 공유해야 하는지(스레드) 따져서 일꾼을 고르는 잣대이다.

</details>

- **실행 단위 선택 기준** 원칙에 따라, 웬만하면 가벼운 **스레드 풀**을 돌리되 치명적인 장애 격리 구간은 **프로세스** 분리 채택 기조 확립함

#### 한줄 요약

- 가볍게 많이 쳐낼 땐 스레드를 돌리고, 죽어도 혼자 죽어야 하는 일은 프로세스로 찢어라.
