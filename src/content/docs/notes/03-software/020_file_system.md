## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **파일 시스템(File System)**: 파일 이름과 메타데이터를 저장장치 블록에 연결하는 영구 저장 관리 체계

</details>

- 정의/개념: **파일 시스템** 은 파일 이름•메타데이터를 저장장치 블록에 연결하고 접근•할당•장애 복구를 관리하는 **영구 저장 관리 체계**
- 배경/필요성: 원시 블록만으로는 파일 **식별•접근 통제•장애 복구 불가**

#### 한줄 요약

- 이름•메타데이터•블록을 연결하는 **영구 저장 체계**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **메타데이터(Metadata)**: 파일의 크기•위치•권한•시간을 설명하는 관리 정보
- **저널링(Journaling)**: 변경 의도를 로그에 기록해 장애 뒤 재실행•복구하는 방식
- **쓰기 시 복사(Copy-on-Write, COW)**: 변경 데이터를 새 블록에 기록한 뒤 참조를 전환하는 갱신 방식
- **디렉터리(Directory)**: 파일 이름과 경로 관계를 관리하는 구조
- **블록(Block)**: 저장장치에 파일 내용을 기록하는 고정 크기 단위
- **내부 단편화(Internal Fragmentation)**: 파일에 배정된 마지막 블록 안에서 사용되지 않고 남는 공간

</details>

- **디렉터리•메타데이터•블록** 분리 관리
- **블록 크기 증가** 시 관리 항목 감소•내부 단편화 증가
- **저널링•COW** 로 장애 일관성 확보

#### 한줄 요약

- 블록 크기와 **관리 비용•내부 단편화**의 절충

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **가상 파일 시스템(Virtual File System, VFS)**: 파일 시스템별 구현 차이를 공통 파일 인터페이스로 추상화하는 계층
- **블록 할당 관리자**: 파일 데이터를 저장할 블록의 배치와 회수를 관리하는 구성요소
- **일관성 관리자**: 데이터•메타데이터 커밋 순서와 장애 복구를 통제하는 구성요소
- **커밋(Commit)**: 관련 데이터•메타데이터 변경이 정한 순서로 영구 저장됐음을 확정하는 동작

</details>

```text
            [애플리케이션]
                   |
        [가상 파일 시스템]
                   |
       [디렉터리•메타데이터]
                   |
         [블록 할당 관리자]
                   |
          [일관성 관리자]
```

선의 의미: 선은 공통 파일 인터페이스, 경로•속성 정보, 블록 배치와 장애 일관성이 결합되는 인접 구성요소의 정적 파일 시스템 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 애플리케이션 | **파일 연산 요청** |
| 가상 파일 시스템 | **공통 파일 인터페이스** |
| 디렉터리•메타데이터 | **경로•속성•위치 연결** |
| 블록 할당 관리자 | **블록 배치•회수** |
| 일관성 관리자 | **커밋•장애 복구 통제** |

#### 한줄 요약

- VFS•메타데이터•블록•**일관성 관리 구조**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **경로•권한 확인**: 디렉터리를 따라 대상을 찾고 쓰기 권한을 검사하는 단계
- **블록 할당**: 파일 변경에 필요한 빈 블록과 기존 매핑을 확보하는 단계
- **일관성 방식 선택**: 직접 갱신•저널링•쓰기 시 복사 중 커밋 방식을 적용하는 단계
- **데이터•복구 정보 기록**: 파일 내용과 저널 또는 새 블록 정보를 영구 저장하는 단계
- **매핑•메타데이터 확정**: 블록 위치•크기•시간과 참조 전환을 커밋하는 단계

</details>

```text
┌──────────────────────────────┐
│ 파일 경로•쓰기 데이터       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 경로•권한 확인           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 블록 할당                │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐

└───────┬──────────────────────┘
        ├─ 직접 갱신
        ├─ 저널링
        └─ 쓰기 시 복사
               │
               ▼

│ 4. 데이터•복구 정보 기록    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐

               ▼
        [완료 바이트•오류 반환]
```

**동작 원리**

- **1. 경로•권한 확인**: 대상 메타데이터와 쓰기 권한 조회
- **2. 블록 할당**: 기존 매핑과 필요한 빈 블록 확보
- **3. 일관성 방식 선택**: 직접 갱신•저널링•COW 적용
- **4. 데이터•복구 정보 기록**: 내용과 장애 복구 정보 저장
- **5. 매핑•메타데이터 확정**: 위치•크기•시간 커밋

#### 한줄 요약

- 블록 기록 후 **복구 정보•메타데이터** 확정

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **파일 할당 테이블(File Allocation Table, FAT)**: 블록 연결을 할당표로 관리하는 파일 시스템
- **신기술 파일 시스템(New Technology File System, NTFS)**: MFT와 ACL 및 저널을 쓰는 파일 시스템
- **4차 확장 파일 시스템(Fourth Extended File System, ext4)**: 아이노드와 익스텐트 및 저널을 쓰는 파일 시스템
- **애플 파일 시스템(Apple File System, APFS)**: COW와 스냅샷을 쓰는 파일 시스템
- **아이노드(Index Node, inode)**: 파일 이름을 제외한 유형•권한•크기•블록 위치를 저장하는 유닉스 계열 구조
- **마스터 파일 테이블(Master File Table, MFT)**: NTFS에서 파일•디렉터리의 속성과 데이터 위치를 레코드로 관리하는 핵심 구조
- **접근 제어 목록(Access Control List, ACL)**: 사용자•그룹별 파일 접근 허용과 거부 권한을 나열한 목록
- **익스텐트(Extent)**: 연속된 여러 저장 블록을 시작 위치와 길이로 표현하는 할당 단위
- **스냅샷(Snapshot)**: 특정 시점의 파일 시스템 상태와 블록 참조를 보존해 그 시점으로 복원할 수 있게 하는 기능

</details>

| 파일 시스템 선택 기준 | FAT | NTFS | ext4 | APFS |
|:---|:---|:---|:---|:---|
| 적용 기준 | **이동식 매체•교차 장치 호환** | **Windows 권한•복구** | **Linux 범용 서버•단말** | **Apple 장치•스냅샷 운영** |
| 핵심 특징 | **단순 할당표•광범위 호환** | **MFT•ACL•저널** | **아이노드•익스텐트•저널** | **COW•스냅샷•암호화** |
| 한계 | **저널 부재•기능 제약** | **Windows 종속성** | **조정 복잡성** | **COW 단편화•생태계 종속** |

> 요약: **호환성•운영체제•복구 방식** 에 따라 **FAT•NTFS•ext4•APFS** 선택

#### 한줄 요약

- 이동식 호환은 FAT, 플랫폼 기능은 **기본 파일 시스템**

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **내구성(Durability)**: 쓰기 완료로 확정한 데이터가 비정상 종료 뒤에도 영구 저장소에 남는 성질
- **강제 동기화(Filesystem Synchronization, fsync)**: 파일 변경 내용을 저장장치까지 확정하도록 요청하는 시스템 호출
- **장애 주입 시험(Fault-injection Test)**: 쓰기 중 전원 차단•오류를 의도적으로 발생시켜 복구를 검증하는 시험
- **쓰기 증폭(Write Amplification)**: 논리 변경량보다 저장장치에 실제 기록되는 데이터가 더 많아지는 현상
- **보존 기간(Retention Period)**: 스냅샷을 유지하는 시간
- **정리 비용(Cleanup Cost)**: 만료 참조와 블록을 회수하는 데 드는 처리량과 시간

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 쓰기 완료를 실제 **내구성 보장으로 오인** | 중요 데이터에 **fsync•장애 주입 시험** 적용 | 장애 후 **데이터 손실 범위** 확인 |
| 작은 파일에 큰 블록을 할당해 **내부 단편화 증가** | 파일 크기 분포에 맞춰 **블록 크기•할당 정책 선택** | **저장 공간 효율** 향상 |
| 장기 스냅샷이 **COW 단편화•쓰기 증폭 유발** | **보존 기간•여유 공간•정리 비용** 관리 | **성능 저하•용량 고갈** 방지 |
| 파일 시스템 기능이 장치•운영체제와 **불일치** | 실제 대상에서 **읽기•쓰기•권한•복구 시험** | **호환성 장애** 예방 |

#### 한줄 요약

- 내구성•단편화•쓰기 증폭을 기준으로 **정책 검증**
