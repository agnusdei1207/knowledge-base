## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파일 시스템(File System)**: 저장 매체 상에 파일과 디렉터리 계층 구조를 생성하고, 메타데이터와 데이터 블록을 매핑하여 영속성을 보장하는 커널 서브시스템.
- **VFS(Virtual File System)**: 서로 다른 파일 시스템(ext4, NTFS, FAT 등)에 대해 일관된 표준 POSIX 시스템 콜(`open`, `read`, `write`)을 제공하는 추상화 계층.

</details>

- 정의/개념: 보조기억장치의 물리 블록에 파일 메타데이터를 부여하여 계층 구조를 관리하고 장애 일관성을 보장하는 **파일 시스템** 아키텍처
- 배경/필요성: 원시 블록에 직접 접근하면 응용마다 블록 위치와 여유 공간을 스스로 관리해야 하고 정전 시 일관성 책임까지 응용에 남으므로, 블록 장치 위에 이름·계층·메타데이터를 부여하는 파일 시스템 계층을 두어 접근 단위를 파일로 추상화할 필요

#### 한줄 요약
- VFS 인터페이스로 스토리지를 추상화하고 메타데이터와 블록 할당, 일관성을 총괄 관리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Inode / MFT**: 리눅스 ext4의 Inode(크기, 권한, 블록 포인터)와 윈도우 NTFS의 MFT(Master File Table, 레코드형 메타데이터).
- **COW(Copy-on-Write)**: 수정 시 원본 블록을 보존하고 새 블록에 쓴 뒤 포인터를 원자적으로 교체하여 무결성을 유지하는 기법.

</details>

- 응용 프로그램과 하위 파일 시스템을 분리하는 **가상 파일 시스템(VFS) 계층** 제공
- 운영체제별 고유 메타데이터 구조: **리눅스 Inode vs 윈도우 MFT**
- 비정상 종료 시 데이터 무결성을 보장하기 위한 **저널링(Journaling) 및 COW(Copy-on-Write)** 지원

#### 한줄 요약
- 파일 시스템은 블록을 이름과 계층으로 추상화하는 대신 메타데이터 갱신과 일관성 유지 비용을 떠안으므로, 저널링과 COW는 그 비용을 어떻게 나눌지의 선택이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Extent(익스텐트)**: 연속된 물리 블록들의 시작 주소와 길이를 한 번에 기록하여 메타데이터 크기를 줄이고 탐색을 가속하는 블록 할당 단위.

</details>

```text
[파일 시스템 4계층 아키텍처]
|-- 사용자 애플리케이션 (POSIX API: open, write, fsync)
|-- VFS 추상화 계층 (Inode, Dentry, File, Superblock 구조체)
|-- 파일 시스템 구현체
|   |-- 메타데이터 관리자 (ext4 Inode / NTFS MFT 레코드)
|   |-- 블록 할당기 (Extent Allocator - 연속 블록 배정)
|   `-- 일관성 트랜잭션 관리자 (JBD2 저널링 / COW B-Tree)
`-- 페이지 캐시 (Page Cache) & 물리 블록 디바이스 드라이버
```

선의 의미: 계층 및 I/O 요청 전달 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| VFS (가상 파일 시스템) | 파일 시스템 구현체에 독립적인 표준 POSIX 인터페이스 제공 |
| 메타데이터 관리자 | 파일 크기, 권한, 소유권, 디스크 블록 주소를 **Inode 또는 MFT**로 관리 |
| 블록 할당기 (Extent) | 연속된 물리 블록 영역(**Extent**)을 파일에 동적 배정하여 단편화 최소화 |
| 일관성 관리자 | 정전 시 복구를 위해 로그를 선행 기록하는 **저널링(WAL)** 또는 **COW** 제어 |
| 페이지 캐시 (Page Cache) | 디스크 I/O 병목 완화를 위해 DRAM에 파일 블록을 캐싱 |

#### 한줄 요약
- VFS가 서로 다른 파일 시스템 구현을 하나의 시스템 호출 인터페이스로 덮기 때문에 응용은 저장 매체를 몰라도 되며, 일관성 관리자는 그 아래에서 정전 시 책임만 따로 진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **fsync()**: 페이지 캐시의 더티 페이지(Dirty Page)와 저널 로그를 물리 스토리지에 즉시 동기화하도록 강제하는 시스템 콜.

</details>

```text
애플리케이션 파일 쓰기 요청 (write() 시스템 콜)
        │
   VFS Dentry 캐시 탐색 및 파일 접근 권한 검증
        │
   페이지 캐시(Dirty Page) 적재 및 Extent 기반 연속 블록 할당
        │
   일관성 보장 방식에 따른 분기
   ┌────┴───────────────────────────┐
[저널링 방식: ext4, NTFS]       [COW 방식: APFS, ZFS]
메타데이터 변경 내역을             새로운 디스크 블록에 데이터 기록 후
저널 로그에 선행 기록 (WAL)       루트 트리 포인터 원자적 교체
   │                                │
   └────┬───────────────────────────┘
        │
   동기화 요청(fsync()) 시 물리 디스크 플러시 및 트랜잭션 커밋 완료
```

#### 한줄 요약
- 저널 선행 기록과 COW는 일관성을 얻는 방식이 다르지만 둘 다 쓰기 양을 늘리며, fsync 호출 시점이 그 비용을 실제로 지불하는 지점이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **In-Place vs Out-of-Place**: 기존 블록을 덮어쓰는 In-Place(ext4/NTFS)와 새 블록에 쓰고 포인터를 바꾸는 Out-of-Place(ZFS/APFS).

</details>

| 파일 시스템 | ext4 (Linux) | NTFS (Windows) | APFS (Apple) | ZFS (Enterprise) | exFAT (Universal) |
|:---|:---|:---|:---|:---|:---|
| 메타데이터 | **Inode + Extents** | **MFT (Master File Table)** | 객체 맵 (Object Map) | 모자이크 트리 (MOS) | File Allocation Table |
| 무결성 기제 | **저널링 (JBD2)** | **저널링 (Log File)** | **COW (Copy-on-Write)** | **COW + 체크섬** | 저널링 미지원 (수동) |
| 스냅샷 지원 | LVM 필요 | VSS 필요 | **원자적 즉시 스냅샷** | **실시간 무제한 스냅샷** | 미지원 |
| 주 적용처 | 리눅스 서버 표준 | 윈도우 OS 표준 | macOS, iOS 플래시 | 엔터프라이즈 스토리지 | USB 이동식 메모리 |

#### 한줄 요약
- 서버 표준은 ext4/NTFS, 무중단 스냅샷과 고신뢰성은 APFS/ZFS, 이동식 호환성은 exFAT를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **O_DIRECT**: OS 커널 페이지 캐시를 우회하여 유저 버퍼와 스토리지를 직결하는 I/O 플래그 (DBMS 필수).
- **TRIM (fstrim)**: 파일 삭제 시 SSD 컨트롤러에 무효화된 LBA 블록을 알려 가비지 컬렉션 효율을 높이는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 급작스런 정전 시 메타데이터 손상 | 저널링 모드(`data=ordered`) 및 **`fsync()` 동기화** 강제 | 부팅 시 초고속 저널 리플레이 복구 및 데이터 무결성 보장 |
| SSD 사용 시 쓰기 증폭(WAF) 및 수명 저하 | 주기적 **TRIM(`fstrim`) 활성화** | SSD 가비지 컬렉션 최적화 및 쓰기 수명 2배 연장 |
| DBMS 운영 시 OS 페이지 캐시와 이중 버퍼링 | 데이터 파일에 **`O_DIRECT` 플래그** 적용 | 커널 메모리 복사 오버헤드 제거 및 DBMS 자체 버퍼 풀 극대화 |
| 대규모 작은 파일 저장 시 Inode 고갈 | 파일 시스템 포맷 시 Inode 밀도(`-i` 옵션) 상향 조정 | 디스크 용량 잔여 상태의 Inode 고갈 오류 방지 |

#### 한줄 요약
- 파일 시스템의 무결성 보장은 쓰기 지연으로 지불되므로, 데이터 유실 허용 폭에 따라 fsync 빈도를 정하고 자체 캐시를 가진 DB는 O_DIRECT로 이중 캐싱 비용을 걷어낸다.

## Ⅶ. 결론

- 서버는 **ext4/XFS**, 고신뢰성 스토리지는 **ZFS** 선택

#### 한줄 요약
- 파일 시스템은 VFS 표준 인터페이스와 저널링/COW 일관성 메커니즘을 통해 데이터의 영속성과 고속 접근을 보장하는 핵심 인프라다.
