## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **File System(파일 시스템)**: 물리적 블록 저장 장치 상에 파일 및 디렉터리 계층 구조를 생성하고, 메타데이터 관리 및 블록 할당을 통해 영속적 데이터 저장과 검색을 제어하는 운영체제 핵심 서브시스템.
- **VFS(Virtual File System, 가상 파일 시스템)**: 하위의 다양한 파일 시스템(ext4, NTFS, FAT 등)에 대해 일관된 시스템 콜 인터페이스(`open`, `read`, `write` 등)를 응용 프로그램에 제공하는 커널 추상화 계층.

</details>

- 정의/개념: 보조기억장치의 물리 블록에 파일 메타데이터를 부여하여 계층적 디렉터리 구조를 형성하고, 무결성과 장애 일관성을 보장하는 **파일 시스템(File System)** 아키텍처
- 배경/필요성: 원시 블록(Raw Block) 스토리지의 직접 접근 한계 극복 및 예기치 않은 시스템 장애 발생 시 **데이터 손실 방지와 무결성 복구 체계 구축** 필요

#### 한줄 요약

- VFS 인터페이스를 통해 다양한 물리 스토리지를 추상화하고 메타데이터와 블록 할당 및 일관성을 관리하는 서브시스템

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Inode(아이노드)**: 유닉스/리눅스 파일 시스템에서 파일명을 제외한 파일 크기, 권한, 소유자, 수정 시간, 실제 데이터 블록 포인터 정보를 저장하는 고유 메타데이터 구조체.
- **MFT(Master File Table)**: 윈도우 NTFS에서 파일과 디렉터리의 모든 속성 및 할당 정보를 레코드 단위로 관리하는 핵심 관계형 구조 메타데이터 테이블.
- **COW(Copy-on-Write)**: 데이터 수정 시 기존 블록을 덮어쓰지 않고 새로운 블록에 기록한 후 포인터를 원자적으로 갱신하여 무결성과 무비용 스냅샷을 보장하는 기법.

</details>

- 응용 프로그램과 물리 파일 시스템 간의 표준 인터페이스를 제공하는 **가상 파일 시스템(VFS) 계층**
- 운영체제 설계 철학에 따른 메타데이터 관리 이원화: **Inode(리눅스 ext4) vs MFT(윈도우 NTFS)**
- 정전 및 비정상 종료 시 무결성을 보장하기 위한 **저널링(Journaling)** 및 **COW(Copy-on-Write)** 메커니즘 지원

#### 한줄 요약

- **VFS 기반 표준 인터페이스·Inode/MFT 메타데이터 관리·저널링/COW 기반 장애 복구성 확보**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Extent(익스텐트)**: 대용량 파일 저장 시 연속된 물리 블록의 시작 번호와 블록 길이를 단일 엔트리로 기록하여 메타데이터 크기를 줄이고 탐색 성능을 높이는 연속 블록 할당 단위.

</details>

```text
[ 파일 시스템 계층 구조 및 입출력 아키텍처 ]
               [ 사용자 응용 프로그램 (Application) ]
                               │ (시스템 콜: open, write, fsync)
                               ▼
              [ 가상 파일 시스템 계층 (VFS) ]
         (Inode, Dentry, File, Superblock 추상 객체)
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
 [ 메타데이터 관리자 (Inode / MFT) ]    [ 블록 할당기 (Extent Allocator) ]
            │                                     │
            └──────────────────┬──────────────────┘
                               ▼
                   [ 일관성 트랜잭션 관리자 ]
                   (JBD2 저널링 / COW 트리)
                               │
                               ▼
                   [ 물리 블록 디바이스 드라이버 ]
```

선의 의미: VFS가 시스템 콜을 수신하여 하위 파일 시스템의 메타데이터 및 블록 할당기를 제어하고, 일관성 계층을 거쳐 물리 드라이버로 전달하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 가상 파일 시스템(VFS) | 하위 파일 시스템 구현체에 독립적인 표준 POSIX 파일 인터페이스 제공 |
| 메타데이터 관리자 | 파일 속성, 권한, 소유권, 디스크 포인터 정보를 Inode 또는 MFT 레코드로 관리 |
| 블록 할당기 (Extent) | 단편화를 최소화하며 물리 디스크의 연속 블록 영역(Extent)을 파일에 동적 배정 |
| 일관성 관리자 | 비정상 종료 시 빠른 복구를 위한 트랜잭션 로그(저널) 기록 또는 COW 스냅샷 갱신 |
| 페이지 캐시(Page Cache) | 디스크 I/O 병목을 완화하기 위해 파일 데이터를 물리 메모리에 캐싱 |

#### 한줄 요약

- **VFS 추상화 계층·메타데이터(Inode/MFT)·익스텐트 블록 할당기·저널링/COW 일관성 관리자**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **fsync()**: 페이지 캐시에 머물러 있는 파일 수정 데이터와 메타데이터를 물리 스토리지에 즉시 동기화 기록하도록 강제하는 시스템 콜.

</details>

```text
[ 파일 쓰기 및 트랜잭션 일관성 보장 시퀀스 ]
 1. 파일 쓰기 요청 (write() 시스템 콜)
          │
          ▼
 2. VFS 권한 및 파일 디스크립터 유효성 검증
          │
          ▼
 3. 페이지 캐시(Dirty Page) 적재 및 Extent 블록 할당
          │
          ▼
 4. 일관성 처리 메커니즘 분기
      ├── [저널링(ext4/NTFS)] ──► 메타데이터 변경 내역을 Journal Log에 선행 기록 (WAL)
      └── [COW(APFS/ZFS)]    ──► 새로운 디스크 블록에 데이터 기록 후 트리 포인터 갱신
          │
          ▼
 5. 동기화 요청 (fsync()) 시 물리 디바이스 플러시 및 Journal Commit 완료
```

**동작 원리**

1. **경로 탐색 및 권한 검증**: VFS가 Dentry 캐시를 통해 파일 경로를 확인하고 사용자 권한을 검증
2. **페이지 캐시 및 블록 할당**: 수정 데이터를 메모리 버퍼(Dirty Page)에 기록하고 Extent 기반으로 연속 블록 할당
3. **일관성 보장 분기**:
   - **저널링**: 실제 메타데이터를 수정하기 전 저널 영역에 변경 로그를 선행 기록(Write-Ahead Logging)
   - **COW**: 원본 블록을 보존한 상태에서 신규 블록에 데이터를 기록하고 파일 시스템 루트 포인터를 원자적 교체
4. **디스크 커밋**: `fsync()` 호출 또는 플러시 데몬 동작 시 물리 디스크에 플러시하여 영속성 확정

#### 한줄 요약

- **권한 검증 $\to$ 페이지 캐시/Extent 할당 $\to$ 저널 선행 기록/COW 갱신 $\to$ fsync 물리 커밋**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Space Sharing(공간 공유)**: APFS 등 최신 파일 시스템에서 물리 컨테이너 내 여러 볼륨이 파티션 크기 제한 없이 가용 용량을 동적으로 공유하는 기능.

</details>

| 비교 항목 | 저널링 기반 (ext4, NTFS) | Copy-on-Write 기반 (APFS, ZFS, Btrfs) | 단순 테이블 기반 (FAT32, exFAT) |
|:---|:---|:---|:---|
| 데이터 갱신 방식 | **In-Place Update** (기존 블록 덮어쓰기) | **Out-of-Place Update** (신규 블록 기록 후 포인터 교체) | In-Place Update |
| 장애 복구 메커니즘 | **저널 로그(Journal Log) 리플레이** | 트리 루트 포인터 원자적 교체 및 롤백 | 파일 할당 테이블 수동 복구(chkdsk/fsck) |
| 스냅샷 지원 | LVM 등 외부 블록 계층 필요 | **포인터 복사 기반 즉각적 스냅샷** 지원 | 미지원 |
| 주 적용 환경 | 고성능 리눅스 서버(ext4), 윈도우 OS(NTFS) | 엔터프라이즈 스토리지(ZFS), 애플 OS(APFS) | USB 플래시 메모리, 임베디드 장치 |

#### 한줄 요약

- 서버 표준 덮어쓰기 성능은 **ext4/NTFS**, 무중단 스냅샷과 고신뢰성은 **APFS/ZFS**, 이동성은 **exFAT**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **O_DIRECT(직접 I/O)**: 커널의 페이지 캐시 계층을 우회하여 사용자 버퍼와 스토리지 장치 간에 직접 데이터를 전송하는 파일 I/O 플래그.
- **TRIM**: 파일 삭제 시 OS가 SSD 컨트롤러에 해당 LBA 블록이 무효화되었음을 통보하여 가비지 컬렉션 오버헤드와 쓰기 증폭(WAF)을 줄이는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 갑작스러운 정전 시 메타데이터 불일치로 인한 **파일 시스템 손상 발생** | 저널링 모드 설정(`data=ordered` 또는 `data=journal`) 및 **`fsync()` 주기적 호출** | 신속한 저널 리플레이 복구 및 데이터 유실 차단 |
| SSD 사용 시 삭제 블록 누적으로 인한 **쓰기 성능 저하 및 수명 단축** | 주기적 **TRIM/Deallocate 명령어 활성화**(`fstrim`) | SSD 가비지 컬렉션 최적화 및 쓰기 증폭(WAF) 억제 |
| DBMS 구동 시 OS 페이지 캐시와 DBMS 버퍼 풀 간의 **이중 버퍼링(Double Buffering) 오버헤드** | DBMS 데이터 파일에 **`O_DIRECT` 플래그 적용** | 커널 캐시 복사 오버헤드 제거 및 DBMS 직접 캐시 제어 확보 |

#### 한줄 요약

- **저널링/fsync 기반 무결성 보장·TRIM 기반 SSD 수명 최적화·O_DIRECT 기반 DBMS 이중 버퍼링 제거**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **File System Selection Strategy**: 운영체제 종류, 스토리지 미디어 특성(HDD/SSD/NVMe), 스냅샷 및 무결성 요구 수준에 따라 최적의 파일 시스템을 선정하는 기준.

</details>

- 리눅스 엔터프라이즈 환경은 검증된 성능의 **ext4/XFS**, 대규모 백업 및 무결성 중심 스토리지는 **ZFS**, 범용 이동식 미디어는 **exFAT** 표준 채택

#### 한줄 요약

- **워크로드 요구(성능, 스냅샷, 이식성)에 부합하는 파일 시스템 선정과 I/O 최적화 기법 적용**
