## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DQM(Data Quality Management)**: 데이터 자산의 유용성과 신뢰성을 확보하기 위해 품질 기준을 수립하고 지속적으로 측정, 개선, 통제하는 체계.
- **6대 핵심 품질 차원**: 완전성(Completeness), 정확성(Accuracy), 일관성(Consistency), 유효성(Validity), 유일성(Uniqueness), 적시성(Timeliness).

</details>

- 정의/개념: 데이터의 비즈니스 유용성과 신뢰성을 보장하기 위해 **6대 품질 진단 차원(완전성, 정확성, 일관성 등)을 정의하고 측정·진단·개선하는 관리 체계**
- 배경/필요성: 불량·오염 데이터가 파이프라인을 통해 하류(Downstream)로 전파될수록 비즈니스 지표 왜곡, AI/ML 모델 환각 및 시스템 장애 복구 비용이 기하급수적으로 폭증하는 한계를 극복하고, 완전성(Completeness), 정확성(Accuracy), 일관성(Consistency), 유효성(Validity), 유일성(Uniqueness), 적시성(Timeliness)의 6대 품질 차원을 기반으로 파이프라인 내에 자동화된 검증 관문(Quality Gate)과 격리(Quarantine) 체계를 구축하여 **데이터 오류의 하류 확산을 원천 차단하고 엔드투엔드 데이터 신뢰성을 보장**할 필요

#### 한줄 요약
- 품질 검증은 적재 속도를 늦추는 비용이지만 그 비용은 오류가 하류로 퍼진 뒤의 정정 비용보다 언제나 작으므로, 관문은 상류에 가까울수록 유리하다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Quality Gate**: 데이터 파이프라인 중간에 배치되어 선언된 품질 기준을 미달한 불량 레코드를 차단하고 격리하는 관문.
- **Great Expectations**: Python/Spark 기반으로 선언적 데이터 품질 검증 룰(Expectations)을 작성하고 자동 리포트를 생성하는 오픈소스 도구.

</details>

- 완전성, 정확성, 일관성, 유효성, 유일성, 적시성의 **6대 핵심 품질 평가 기준 수립**
- 파이프라인 내 불량 데이터의 하류 전파를 차단하는 **자동화된 Quality Gate 배치**
- 프로파일링 $\to$ 진단 $\to$ 격리 $\to$ 원인 개선으로 이어지는 **폐루프(Closed-Loop) 품질 순환**

#### 한줄 요약
- 6대 품질 차원 진단과 자동화된 관문 통제를 통해 고품질 데이터를 지속 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DQM 6대 평가 차원**: 완전성(Null 0%), 정확성(참값 일치), 일관성(상충 0%), 유효성(포맷 준수), 유일성(중복 0%), 적시성(SLA 준수).

</details>

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 완전성 (Completeness) | 필수 비즈니스 항목의 **Null, 공백, 미입력 결측치 비율 측정 및 차단** | `IS NOT NULL` 검증 |
| 정확성 (Accuracy) | 수집된 데이터가 **실제 현실 참값 및 비즈니스 공식과 일치하는지 측정** | 참조 테이블 대조 |
| 일관성 (Consistency) | 원천 시스템과 DW/레이크 간 **동일 개체 데이터의 표현 및 의미 상충 여부 진단** | 시스템 간 대사 검증 |
| 유효성 (Validity) | 주민번호, 날짜 형식 등 **정의된 도메인 규칙 및 정규식 포맷 준수 여부 판정** | Regex 포맷 검증 |
| 유일성 (Uniqueness) | 업무 기본키(PK) 및 비즈니스 식별자의 **의도치 않은 중복 행 발생 여부 탐지** | 중복 제거 룰 적용 |
| 적시성 (Timeliness) | 요구된 비즈니스 목표 시간(SLA) 내에 **데이터가 지연 없이 서빙되었는지 측정** | 지연 Latency 측정 |

#### 한줄 요약
- 완전성, 정확성, 일관성, 유효성, 유일성, 적시성의 6대 차원으로 데이터를 평가한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **폐루프 품질 관리 5단계**: 프로파일링 $\to$ 규칙 적용 $\to$ 하류 통과 / 격리 $\to$ 원인 분석 $\to$ 상류 소스 개선.

</details>

```text
파이프라인을 통해 원천 데이터 유입
        │
   [품질 프로파일링] 컬럼별 결측치 비율, Distinct 카디널리티, 분포 통계 자동 추출
        │
   [Quality Gate 검증] Great Expectations 선언적 룰셋 기반 품질 검증 실행
   ┌────┴───────────────────────────┐
  예 (품질 검증 통과)               아니오 (품질 기준 미달)
   │                                 │
[하류 저장소 서빙]                [Quarantine 격리 및 알림]
Delta Lake 실버 계층 승격         오류 레코드를 격리 테이블에 분리 후
및 BI/AI 모델에 데이터 제공       Slack으로 데이터 엔지니어에게 알림
        │                               │
   └────┬───────────────────────────┘
         ▼
    Data Lineage를 역추적하여 상류 소스 버그를 수정하고 검증 룰 재실행
```

#### 한줄 요약
- 규칙을 엄격히 걸면 불량 유입은 막히지만 정상 데이터까지 격리돼 지표가 비고 느슨히 걸면 통과량은 유지되나 오염이 남으므로, 임계값 설정 자체가 곧 품질 정책이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **수동 점검 vs 자동화 DQM**: 사후 대응 방식의 수동 쿼리 점검과 실시간 차단 기반의 자동화 DQM 플랫폼.

</details>

| 비교 항목 | 전통적 수동 점검 (Manual DQ) | 현대적 자동화 DQM 플랫폼 (Automated) |
|:---|:---|:---|
| 품질 검증 시점 | **사후 점검 (사용자가 오류 보고 후 수동 쿼리)**| **사전/실시간 (파이프라인 내 Quality Gate 탑재)** |
| 오류 데이터 처리 | 타깃 DB에 이미 오염 데이터 적재 완료 | **Quarantine 격리 테이블로 즉시 자동 차단** |
| 검증 룰 관리 | 개별 개발자의 일회성 SQL 스크립트 | **Git 기반 버전 관리되는 선언적 코드(Expectations)**|
| 대표 도구 | Excel, 수동 Ad-hoc SQL | **Great Expectations, Soda Core, Databricks DLT** |

#### 한줄 요약
- 사후 수동 대응을 탈피하고 파이프라인 내 자동화된 Quality Gate를 구축한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Alert Fatigue**: 품질 검증 임계치를 너무 엄격하게 설정하여 매일 수백 건의 무의미한 에러 알림이 쏟아져 엔지니어가 무시하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 노이즈성 알림 폭증으로 엔지니어가 무시하는 **Alert Fatigue** | **핵심 SLA 중심 임계치 상향 및 알림 등급(Warning/Error) 세분화** | 실질적 크리티컬 장애 집중 대응 |
| 1건의 사소한 불량 데이터로 대규모 파이프라인 중단 | **`ON VIOLATION DROP ROW` 설정으로 오류 행만 격리 후 계속 실행** | 파이프라인 가용성 확보 |
| 결함 데이터 발생 시 원인 추적 지연 | **Data Lineage(데이터 계보)와 연동하여 오류 발생 상류 작업 즉시 특정**| 장애 원인 규명 시간 80% 단축 |
| 비즈니스 규칙 변경 시 낡은 품질 룰로 인한 오탐 | **데이터 품질 룰셋을 CI/CD 파이프라인과 통합하여 버전 동기화** | 품질 검증 신뢰도 100% 유지 |

#### 한줄 요약
- 알림 등급 세분화, 행 단위 격리 실행, 계보 기반 원인 역추적, 룰셋 버전 관리로 운영한다.

## Ⅶ. 결론

- 엔터프라이즈 AI 및 비즈니스 인텔리전스의 성패를 좌우하는 **가장 핵심적인 데이터 신뢰성 방어 체계**로 확립되었으며, 실무 구축 시에는 **Great Expectations/Soda 기반의 선언적 룰셋 버전 관리, 파이프라인 중단을 방지하면서 불량 행만 선별 격리하는 Quarantine 아키텍처, 알림 피로(Alert Fatigue)를 방지하는 단계별 임계치 거버넌스, 데이터 계보(Lineage)와 결합한 상류 원인 즉각 역추적 체계**를 유기적으로 가동하여 데이터 품질 폐루프(Closed-Loop) 개선을 완성

#### 한줄 요약
- 데이터 품질 관리는 6대 품질 차원과 자동화된 검증 관문을 통해 데이터 오류의 하류 전파를 차단하고 신뢰성을 완성하는 데이터 엔지니어링의 핵심 통제 체계다.
