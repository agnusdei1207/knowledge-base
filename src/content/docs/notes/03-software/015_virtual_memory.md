## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **가상 메모리(Virtual Memory)**: 프로세스의 가상 주소를 물리 메모리와 후면 저장소에 연결하는 메모리 관리 기법이다.

</details>

- 정의/개념: **가상 메모리**는 프로세스의 가상 주소를 물리 메모리와 후면 저장소에 매핑해 독립된 주소 공간을 제공하는 메모리 관리 기법이다.
- 배경/필요성: 프로세스가 물리 메모리 배치를 직접 관리하면 격리•재배치•탄력적 할당이 제약된다.

#### 한줄 요약

- 독립 가상 주소를 물리 메모리와 후면 저장소에 연결한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **요구 페이징(Demand Paging)**: 실제 참조한 페이지가 없을 때만 후면 저장소에서 메모리로 적재하는 방식이다.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 가상•물리 주소 변환 결과를 보관하는 캐시이다.
- **페이지 테이블(Page Table)**: 가상 페이지의 물리 프레임•접근 권한•상주 여부를 기록하는 표이다.

</details>

- 가상•물리 주소 분리로 프로세스별 주소 공간을 격리한다.
- **요구 페이징**으로 필요한 페이지만 물리 메모리에 적재가 핵심이다.
- **페이지 테이블**과 **TLB**로 주소를 변환하고 권한을 검사한다.

#### 한줄 요약

- 주소 공간 격리와 **요구 페이징** 기반 탄력적 할당이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: 가상 주소를 물리 주소로 변환하고 접근 권한을 검사하는 장치이다.
- **후면 저장소(Backing Store)**: 비상주 페이지를 보관하는 보조기억장치이다.
- **페이지 폴트 처리기(Page-fault Handler)**: 페이지 부재면 적재•매핑 갱신 후 명령을 재실행하고 권한 위반이면 접근을 차단하는 커널 구성요소이다.

</details>

```text
                [프로세서]
                    |
                [MMU•TLB]
                    |
             [페이지 테이블]
                    |
          [페이지 폴트 처리기]
                    |
      [물리 메모리•후면 저장소]
```

선의 의미: 선은 가상 주소 변환, 매핑 정보, 폴트 처리와 상주•비상주 저장 공간이 결합되는 인접 구성요소의 정적 메모리 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 | 가상 주소•접근 생성 |
| MMU•TLB | 변환 조회•권한 검사 |
| 페이지 테이블 | 프레임•권한•상주 저장 |
| 페이지 폴트 처리기 | 부재•위반 처리 |
| 물리 메모리•후면 저장소 | 상주•비상주 페이지 보관 |

#### 한줄 요약

- **MMU**, **페이지 테이블**, **페이지 폴트 처리기**가 주소 변환 구조를 이룬다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **TLB 조회**: 최근 가상•물리 주소 변환과 접근 권한을 캐시에서 찾는 단계이다.
- **페이지 테이블 워크**: TLB 미스 시 계층 페이지 테이블에서 매핑을 탐색하는 단계이다.
- **변환 상태 판정**: 매핑의 상주 여부와 읽기•쓰기•실행 권한을 확인하는 단계이다.
- **물리 메모리 접근**: 변환된 물리 주소로 데이터나 명령을 읽고 쓰는 단계이다.
- **페이지 폴트 처리**: 비상주 페이지를 적재해 매핑을 갱신하거나 권한 위반을 차단하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 가상 주소•접근 유형         │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. TLB 조회                 │◀──────────────┐
└───────┬──────────────────────┘               │
        ├─ 히트 ─────────────────┐             │
        │ 미스                   │             │
        ▼                        │             │
┌──────────────────────────────┐│             │
│ 2. 페이지 테이블 워크       ││             │
└──────────────┬───────────────┘│             │
               └────────────────┤             │
                                ▼             │
┌──────────────────────────────┐              │
│ 3. 변환 상태 판정           │              │
└───────┬──────────────────────┘              │
        ├─ 권한 위반 ─────────────▶ [접근 차단]
        ├─ 상주•허용 ─────────────▶ [4. 물리 메모리 접근]
        │ 비상주                               │
        ▼                                      │
┌──────────────────────────────┐              │
│ 5. 페이지 폴트 처리         │              │
│ 적재•매핑 갱신              │──────────────┘
└──────────────────────────────┘   명령 재실행
```

### 동작 원리

1. **TLB 조회**: 캐시된 주소 변환•권한을 탐색한다.
2. **페이지 테이블 워크**: TLB 미스 시 계층 매핑을 조회한다.
3. **변환 상태 판정**: 상주 여부•접근 권한으로 분기한다.
4. **물리 메모리 접근**: 변환된 프레임에 연산을 수행한다.
5. **페이지 폴트 처리**: 페이지 적재•매핑 갱신 후 재실행한다.

#### 한줄 요약

- TLB 미스•페이지 부재에 따라 변환과 적재를 수행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **페이징(Paging)**: 가상 페이지를 같은 크기의 물리 프레임에 매핑하는 고정 크기 분할 방식이다.
- **세그멘테이션(Segmentation)**: 코드•데이터•스택을 가변 크기 논리 영역으로 나누는 분할 방식이다.
- **내부 단편화(Internal Fragmentation)**: 고정 블록 내부에 남는 사용 불가 공간이다.
- **외부 단편화(External Fragmentation)**: 가변 영역 사이에 흩어진 연속 사용 불가 공간이다.

</details>

| 메모리 분할 방식 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 적용 기준 | 비연속 메모리의 균일 할당 | 논리 영역별 보호•공유 |
| 핵심 특징 | 고정 페이지•비연속 프레임 | 가변 논리 영역•연속 공간 |
| 한계 | **내부 단편화**•페이지 테이블 비용 | **외부 단편화**•연속 공간 필요 |

> 요약: **비연속 할당**은 페이징, **논리 영역 보호**는 세그멘테이션이 핵심이다.

#### 한줄 요약

- 비연속 할당은 **페이징**, 논리 보호는 **세그멘테이션**이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **쓰기•실행 분리(Write XOR Execute, W^X)**: 한 페이지에 쓰기와 실행 권한을 동시에 허용하지 않는 원칙이다.
- **주소 공간 배치 무작위화(Address Space Layout Randomization, ASLR)**: 코드•데이터•스택 주소를 실행마다 바꾸는 보호 기법이다.
- **대형 페이지(Huge Page)**: 하나의 TLB 항목이 더 넓은 메모리 범위를 변환하도록 키운 페이지이다.
- **워킹 셋(Working Set)**: 프로세스가 최근 반복 참조해 메모리에 유지할 필요가 있는 페이지 집합이다.
- **TLB 무효화(TLB Invalidation)**: 페이지 매핑 변경 때 오래된 TLB 변환 항목을 제거하는 동작이다.
- **주요 페이지 폴트(Major Page Fault)**: 요구 페이지를 저장장치에서 읽어야 해 큰 지연이 발생하는 페이지 폴트이다.
- **교환량(Swap Volume)**: 메모리와 저장장치 사이를 이동한 페이지 양이다.
- **수용 제어(Admission Control)**: 메모리 여유에 따라 새 작업 허용을 정하는 절차이다.
- **스레싱(Thrashing)**: 워킹 셋이 메모리에 머물지 못해 페이지 교체가 실제 실행을 압도하는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 쓰기•실행 권한을 함께 부여해 코드 주입 위험 증가 | **W^X**•**ASLR**과 페이지별 최소 권한 적용 | 메모리 공격면 축소 |
| **대형 페이지**가 내부 단편화•회수 지연 유발 | TLB 미스•사용률•회수 비용에 따라 선택 적용 | 변환 성능•회수 유연성 균형 |
| 메모리 압박으로 교환•**주요 페이지 폴트** 급증 | **워킹 셋**•**교환량** 감시와 한도•**수용 제어** | **스레싱** 예방 |
| 매핑 변경이 잦아 **TLB 무효화** 비용 확대 | 변경을 묶어 처리하고 무효화 지연 계측 | 다중 코어 확장성 향상 |

#### 한줄 요약

- 권한•폴트•TLB 비용을 함께 고려해 페이지 정책을 정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **비연속 할당**: 고정 크기 페이지 매핑을 선택하는 기준이다.
- **논리 영역 보호**: 가변 크기 세그멘테이션을 선택하는 기준이다.
- **메모리 분할 선택 기준**: 비연속 할당과 논리 영역 보호 요구에 따라 분할 방식을 고르는 기준이다.

</details>

- **메모리 분할 선택 기준**에 따라 **비연속 할당**은 **페이징**, **논리 영역 보호**는 **세그멘테이션**을 적용한다.

#### 한줄 요약

- 비연속 할당과 논리 보호에 맞는 분할 방식을 선택한다.
