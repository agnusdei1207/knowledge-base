## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **고정 페이징 및 가변 세그멘테이션(Paging & Segmentation)**: 4KB 고정 블록 단위로 비연속 매핑하는 페이징과 논리적 코드/데이터/스택 단위로 분할 관리하는 세그멘테이션.
- **데이터 오염 및 단편화(Corruption & Fragmentation)**: 격리 없는 물리 주소 직접 접근 시 발생하는 프로세스 간 침범 오염 및 내부/외부 메모리 낭비 현상.

</details>

- 정의/개념: 물리 메모리 한계를 넘어선 연속 논리 주소 공간을 제공하기 위해 **고정 크기(Paging) 및 가변 크기(Segmentation)** 로 분할 매핑하는 메모리 관리 체계
- 배경/필요성: 물리 RAM 크기 제약 극복 및 프로세스 간 메모리 격리와 단편화 최소화 필요

#### 한줄 요약

- 물리 메모리를 초과하는 논리 주소 공간을 각 프로세스에 독립적으로 제공하는 가상 메모리를 페이징과 세그멘테이션으로 구현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MMU(Memory Management Unit)**: 논리 주소를 물리 주소로 변환하고 접근 권한을 검증하는 하드웨어 주소 변환 장치.
- **페이지 테이블(Page Table)**: 가상 페이지 번호(VPN)를 물리 프레임 번호(PFN)로 매핑하는 커널 자료 구조.
- **TLB(Translation Lookaside Buffer)**: 최근 주소 변환 결과를 캐시하여 페이지 테이블 탐색 없이 물리 주소를 고속 조회하는 MMU 내부 캐시.

</details>

- 프로세스별 독립 논리 주소 공간으로 메모리 격리 보장
- 고정 크기(4KB) 분할 **페이징**(내부 단편화 발생)과 가변 크기 분할 **세그멘테이션**(외부 단편화 발생)으로 구현
- **MMU·TLB·페이지 테이블** 3계층으로 실시간 주소 변환 및 접근 권한 제어

#### 한줄 요약

- 프로세스별 독립 가상 주소 공간을 MMU·TLB·페이지 테이블로 물리 주소로 변환하여 메모리를 관리

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 고정 크기 페이지 할당 시 페이지 내 사용하지 않는 공간이 낭비되는 현상.
- **외부 단편화(External Fragmentation)**: 가변 크기 세그멘테이션 시 빈 공간이 비연속으로 분산되어 연속 할당 요청을 수용하지 못하는 현상.

</details>

```text
[ 가상 메모리 주소 변환 구조 ]
CPU (가상 주소 발급)
   │
   ▼
MMU + TLB (고속 주소 변환 캐시)
├─ TLB 히트: 물리 주소 즉시 반환
└─ TLB 미스: 페이지 테이블 워크
    ├─ 다단계 페이지 테이블 탐색
    └─ 세그먼트 테이블 탐색 (세그멘테이션)
페이지 폴트 처리기
└─ 물리 메모리 미적재 시 Swap 디스크에서 적재
```

선의 의미: 가지(`├─`, `└─`)는 TLB 히트·미스에 따른 주소 변환 경로 분기 관계

| 구성요소 | 책임 |
|:---|:---|
| MMU + TLB | 가상→물리 주소 고속 변환 및 접근 권한 검증 |
| 다단계 페이지 테이블 | VPN→PFN 매핑 정보 계층적 보관 (메모리 공간 절약) |
| 세그먼트 테이블 | 세그먼트 기준 주소·한계·접근 권한 보관 |
| 페이지 폴트 처리기 | 물리 메모리 미적재 페이지를 Swap에서 적재 후 재실행 |

#### 한줄 요약

- MMU·TLB가 1차 고속 변환하고 미스 시 페이지 테이블 워크, 물리 메모리 미적재 시 폴트 처리기가 Swap에서 적재

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 테이블 워크(Page Table Walk)**: TLB 미스 발생 시 MMU가 다단계 페이지 테이블을 순차 탐색하여 물리 프레임 번호를 산출하는 과정.

</details>

```text
CPU: 가상 주소(VA) 발급
   │
   ▼
1. TLB 조회 (VA→PA 캐시 탐색)
├─ 히트: PA 즉시 획득 → 4단계로 이동
└─ 미스
      │
      ▼
   2. 페이지 테이블 워크 (메모리 내 다단계 탐색)
   ├─ 엔트리 유효: PA 획득 → TLB 갱신 → 4단계
   └─ 엔트리 무효 (물리 메모리 미적재)
         │
         ▼
      3. 페이지 폴트 처리 (Swap→물리 메모리 적재)
         └─ 페이지 테이블 갱신 후 1단계 재실행
   │
   ▼
4. 접근 권한 검증
├─ 위반: 세그멘테이션 폴트(접근 차단)
└─ 정상: 물리 메모리 접근 완료
```

**동작 원리** 1. **TLB 조회**: MMU가 TLB에서 가상 페이지 번호를 고속 조회하여 물리 주소를 산출
2. **페이지 테이블 워크**: TLB 미스 시 다단계 페이지 테이블을 순차 탐색하여 물리 프레임 번호 획득
3. **페이지 폴트 처리**: 물리 메모리 미적재 시 Swap 영역에서 페이지를 적재하고 페이지 테이블을 갱신
4. **접근 권한 검증**: MMU가 Write/Execute 권한을 검증하여 위반 시 세그멘테이션 폴트 발생

#### 한줄 요약

- TLB→페이지 테이블→Swap 순서로 주소를 변환하고, 접근 권한 위반 시 폴트를 발생

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이징된 세그멘테이션(Paged Segmentation)**: 세그먼트를 논리 단위로 분할하고 각 세그먼트 내부를 페이지로 재분할하여 외부 단편화 없이 보호·공유 속성을 세그먼트 단위로 부여하는 혼합 기법.

</details>

| 구분 | 페이징 | 세그멘테이션 | 페이징된 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | 외부 단편화 제거·간단 구현 필요 시 | 논리 단위 보호·공유 속성 부여 필요 시 | 보호·공유와 단편화 제거를 동시 요구 시 |
| 핵심 특징 | 4KB 고정 분할·**내부 단편화** 발생 | 가변 분할·**외부 단편화** 발생 | 세그먼트 보호 + 페이지 비연속 할당 |
| 한계 | 세그먼트 논리 구조 미반영 | 할당·해제 반복 시 빈 공간 파편화 심화 | 페이지 테이블·세그먼트 테이블 이중 관리 오버헤드 |

#### 한줄 요약

- 단편화 제거 우선이면 페이징, 논리 단위 보호 우선이면 세그멘테이션, 둘 다 필요하면 페이징된 세그멘테이션 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대용량 페이지(HugePages)**: 4KB 기본 페이지 대신 2MB/1GB 대형 페이지를 사용하여 TLB 엔트리 수를 줄이고 TLB 미스율을 감소시키는 기법.
- **메모리 압축(Memory Compaction/zRAM)**: Swap 디스크 대신 물리 메모리 내에서 비활성 페이지를 압축 보관하여 Swap I/O 지연을 회피하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 메모리 사용 시 **TLB 미스** 급증으로 주소 변환 오버헤드 증가 | **대용량 페이지(HugePages)** 적용 | TLB 엔트리 커버리지 확대로 TLB 미스율 감소 |
| 64비트 주소 공간 기반 단순 페이지 테이블의 메모리 과다 점유 | **다단계 페이지 테이블** 도입으로 미사용 영역 테이블 생략 | 페이지 테이블 메모리 소비 절감 |
| 세그멘테이션 반복 할당·해제로 **외부 단편화** 누적 | **메모리 압축(Compaction)** 또는 페이징과 혼합 사용 | 연속 가용 공간 확보 |

#### 한줄 요약

- TLB 미스는 HugePages로, 테이블 메모리 과다는 다단계 테이블로, 외부 단편화는 압축으로 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상 메모리 아키텍처 선택 기준**: 물리 메모리 크기·TLB 압박·단편화 허용 수준에 따라 페이징 방식과 대용량 페이지 적용 여부를 결정하는 판단 기준.

</details>

- 범용 OS는 **다단계 페이징**, 대용량 엔터프라이즈 DB는 **HugePages** 선택

#### 한줄 요약

- 범용 환경은 다단계 페이지 테이블로 메모리를 절약하고, 고성능 DB 환경은 HugePages로 TLB 미스를 감소
