## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 실제 물리 RAM 크기와 무관하게 프로세스마다 독립적이고 연속된 논리 주소 공간을 제공하는 메모리 가상화 기법.
- **페이징 vs 세그멘테이션**: 4KB 고정 블록 단위로 분할하는 페이징(Paging)과 논리적 의미 단위(Code/Data/Stack)로 가변 분할하는 세그멘테이션(Segmentation).

</details>

- 정의/개념: 물리 메모리를 초과하는 논리 주소 공간을 프로세스에 제공하기 위해 **고정 분할(Paging) 및 가변 분할(Segmentation)** 로 주소를 매핑하는 메모리 관리 체계
- 배경/필요성: 초기 시스템에서 프로세스가 물리 메모리 주소를 직접 참조할 때 발생하던 물리 RAM 용량 한계($\le \text{DRAM}$), 외부 단편화에 따른 연속 메모리 할당 실패 및 프로세스 간 메모리 무단 침범 위험을 극복하고, CPU MMU와 다단계 페이지 테이블을 통해 프로세스별 독립 64비트 가상 주소 공간을 제공함으로써 **물리 메모리 이상의 대용량 공간 활용과 완벽한 프로세스 메모리 격리 및 보호를 실현**할 필요

#### 한줄 요약
- 프로세스마다 독립된 가상 주소 공간을 부여하고 MMU를 통해 물리 메모리로 매핑한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MMU(Memory Management Unit)**: CPU가 발급한 가상 주소를 물리 주소로 실시간 변환하고 메모리 접근 권한을 검증하는 하드웨어 칩셋.
- **TLB(Translation Lookaside Buffer)**: 가상 페이지 번호(VPN)와 물리 프레임 번호(PFN) 매핑을 캐싱하는 MMU 내부 고속 연관 메모리.

</details>

- 프로세스별 독립 64비트 가상 주소 공간을 통한 완벽한 메모리 결함 및 보안 격리
- 고정 분할 **페이징(내부 단편화 발생)** 과 논리 가변 분할 **세그멘테이션(외부 단편화 발생)** 의 기법적 대비
- **MMU, TLB 캐시, 다단계 페이지 테이블** 3계층 하드웨어/소프트웨어 주소 변환 협력

#### 한줄 요약
- 가상 메모리는 용량 확장과 격리를 주소 변환 단계와 페이지 폴트 가능성으로 지불하며, TLB는 그중 변환 비용만 다시 줄이는 사본 계층이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **다단계 페이지 테이블(Multi-Level Page Table)**: 64비트 방대한 주소 공간에서 미사용 영역의 페이지 테이블 생성을 생략하여 메모리를 대폭 절약하는 트리형 계층 구조.

</details>

```text
[가상 메모리 주소 변환 및 하드웨어 아키텍처]
|-- CPU 코어 (논리 가상 주소 발급: Virtual Address)
|-- MMU 하드웨어
|   |-- TLB 캐시 (VPN -> PFN 고속 변환, 1 사이클 히트)
|   `-- 페이지 테이블 워커 (TLB 미스 시 CR3 레지스터 기준 순회)
|-- 4단계 페이지 테이블 (PGD -> PUD -> PMD -> PTE)
`-- 물리 메모리 (DRAM) & 스왑 디스크 (Swap Space)
    |-- 물리 프레임 (Physical Frame)
    `-- 페이지 폴트 처리기 (Page Fault Handler - 스왑 I/O)
```

선의 의미: 계층 및 가상-물리 주소 변환 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| MMU (하드웨어) | 가상 주소를 물리 주소로 실시간 변환하고 권한(R/W/X) 위반 시 트랩 발생 |
| TLB 캐시 | 최근 변환된 VPN $\to$ PFN 엔트리를 보관하여 메모리 접근 지연 최소화 |
| 다단계 페이지 테이블 | 계층적(PGD/PUD/PMD/PTE) 포인터 구조로 메모리 매핑 장부 크기 절약 |
| 페이지 폴트 처리기 | 물리 메모리에 없는 무효 페이지 접근 시 디스크 스왑에서 DRAM으로 페이지 인입 |

#### 한줄 요약
- MMU와 페이지 테이블이 주소 공간과 물리 프레임 사이를 끊어 놓기 때문에 용량 확장과 보호가 같은 장치에서 함께 나오며, 페이지 폴트 처리기가 그 단절을 메우는 예외 경로가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 테이블 워크(Page Table Walk)**: TLB 미스 시 MMU 하드웨어가 메인 메모리의 4단계 페이지 테이블을 차례로 탐색하여 물리 주소를 알아내는 과정.

</details>

```text
CPU가 명령어/데이터 가상 주소(VA) 접근 요청
        │
   MMU 내부 TLB 캐시를 조회
   ┌────┴─────┐
  TLB 적중(Hit)  TLB 미스(Miss)
   │             │
물리 주소 즉시 획득  MMU가 CR3 레지스터를 시작으로 다단계 페이지 테이블 탐색 (Page Walk)
   │             │
   │        해당 페이지의 유효 비트(Valid Bit)가 1인가?
   │        ┌────┴─────┐
   │       예           아니오 (Valid Bit = 0)
   │        │             │
   │   물리 주소 도출    하드웨어 페이지 폴트(Page Fault) 인터럽트 발생
   │   및 TLB 갱신        │
   │        │        디스크 스왑 영역에서 해당 페이지를 물리 프레임에 적재
   │        │        후 페이지 테이블 Valid Bit를 1로 갱신
   │        │             │
   └────┬───┴─────────────┘
        │
   접근 권한(Read/Write/Execute) 검증 통과 후 물리 메모리 접근 완료
```

#### 한줄 요약
- TLB 적중은 클록 단위, Page Walk는 메모리 접근 단위, Page Fault는 디스크 I/O 단위로 지연 자릿수가 달라지므로, 같은 참조라도 어느 갈래를 타는지가 성능을 지배한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지드 세그멘테이션(Paged Segmentation)**: 프로그램을 논리 세그먼트로 나누고, 각 세그먼트 내부를 다시 고정 크기 페이지로 분할하여 외부 단편화를 없앤 혼합형 기법.

</details>

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 페이지드 세그멘테이션 |
|:---|:---|:---|:---|
| 분할 단위 | **고정 크기 블록 (4KB/2MB)** | **가변 크기 논리 단위 (함수/배열)** | 가변 세그먼트 내 고정 페이지 |
| 단편화 발생 | **내부 단편화 발생** (외부 단편화 전무) | **외부 단편화 발생** (내부 단편화 전무) | 내부 단편화만 소량 발생 |
| 공유 및 보호 | 페이지 단위 (보호 속성 지정 번거로움) | **논리 단위 공유/보호 매우 용이** | 논리 단위 보호 + 페이지 단위 할당 |
| 주소 변환 장부 | 다단계 페이지 테이블 | 세그먼트 테이블 (Base/Limit) | 세그먼트 테이블 + 페이지 테이블 |
| 현대 OS 채택 | **Linux / Windows 사실상 표준** | x86 Flat 모델로 거의 비활성화 | 과거 OS 및 가상화 하이퍼바이저 |

#### 한줄 요약
- 외부 단편화 방지는 페이징, 논리적 보호는 세그멘테이션, 현대 OS는 순수 페이징을 표준 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **HugePages**: 기본 4KB 대신 2MB 또는 1GB 크기의 거대 페이지를 사용하여 TLB 엔트리 커버리지를 비약적으로 넓히는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수백 GB 대규모 메모리 DB에서 **TLB 미스** 빈발 지연 | **HugePages(2MB / 1GB)** 활성화 | TLB 커버리지 500배 확장 및 주소 변환 오버헤드 80% 절감 |
| 64비트 단일 페이지 테이블의 메모리 과소비 | **다단계 페이지 테이블(4-Level / 5-Level)** 도입 | 미사용 가상 주소 영역의 페이지 테이블 할당 생략 |
| 포크(fork) 시 전체 메모리 복사 오버헤드 | **COW(Copy-On-Write)** 지연 복사 기법 적용 | 프로세스 생성 즉각 완료 및 물리 메모리 중복 낭비 방지 |
| 스왑 I/O 지연으로 인한 애플리케이션 레이턴시 스파이크 | **`mlockall()`** 시스템 콜로 핵심 메모리 잠금 | 필수 코드/데이터의 디스크 스왑아웃 원천 차단 |

#### 한줄 요약
- 가상 메모리의 용량 확장과 보호는 주소 변환과 페이지 폴트 비용을 대가로 얻은 것이므로, HugePages로 변환 비용을 줄이고 지연에 민감한 영역만 mlock으로 스왑 대상에서 빼낸다.

## Ⅶ. 결론

- 현대 운영체제 및 컴퓨터 아키텍처의 **가장 핵심적인 메모리 격리·보호·가상화 표준 기술**로 확립되었으며, 실무 고성능 환경에서는 **기본 4단계(4-Level/5-Level) 페이징 체계와 더불어, DBMS/AI 대규모 인메모리 연산의 TLB 미스 오버헤드를 80% 이상 절감하는 HugePages(2MB/1GB), fork 지연을 없애는 COW(Copy-On-Write) 및 실시간 메모리 고정(`mlockall`)**을 결합하여 성능을 극대화

#### 한줄 요약
- 가상 메모리는 페이징 기법과 MMU/TLB 하드웨어의 협력을 통해 무한한 논리 주소 공간과 완벽한 프로세스 격리를 제공하는 현대 OS의 핵심 기둥이다.
