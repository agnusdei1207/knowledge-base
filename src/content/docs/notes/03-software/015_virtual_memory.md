## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 램(RAM) 용량이 작아도 하드디스크를 끌어와서 각 프로세스한테 "너 혼자 메모리 다 쓰는 거야"라고 뻥카를 쳐주는 메모리 사기 기술이다.
- **페이징(Paging)**: 메모리를 4KB짜리 똑같은 크기의 네모난 타일(페이지/프레임)로 칼같이 쪼개서, 남는 빈칸 없이 쑤셔 박는 평등주의 분할 기법이다.
- **세그멘테이션(Segmentation)**: 코드, 데이터, 스택 같은 쓰임새(의미)에 따라 메모리를 가변 크기로 뭉텅뭉텅 잘라서 관리하는 계급주의 분할 기법이다.

</details>

- 정의: 물리적 램(RAM) 크기의 한계를 속이고, 논리 주소를 물리 주소로 자동 번역해 주는 **가상 메모리** 매커니즘과 그 구현체인 **페이징 & 세그멘테이션**
- 배경: 프로그램 덩치가 너무 커져서 제한된 **물리 메모리** 크기에 맞춰 프로그램을 통째로 올리는 건 불가능해졌기 때문

#### 한줄 요약

- 진짜 램 용량을 속이고 하드디스크를 합쳐서 무한대처럼 쓰게 해주는 기술로, 메모리를 네모 반듯하게 썰면 페이징, 용도별로 썰면 세그멘테이션이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: 가짜 주소(가상 주소)를 진짜 주소(물리 주소)로 바꿔주고, 남의 메모리 건드리면 권한 밖이라며 철퇴를 내리는 빡센 하드웨어 문지기이다.
- **페이지 테이블(Page Table)**: 가상 페이지 번호가 진짜 물리 메모리 몇 번 프레임에 있는지 맵핑 정보를 적어둔 방대한 메모리 호적부이다.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 호적부(페이지 테이블)까지 가기 귀찮아서 MMU 안에 짱박아둔 초고속 VIP 주소록(캐시)이다.

</details>

- 프로세스마다 주소 공간을 독립시켜 다른 놈이 못 훔쳐보게 철저히 격리(Isolation)함.
- 크기를 똑같이 썰어서 쑤셔 넣는 **페이징(내부 단편화 터짐)**과 의미대로 썰어 넣는 **세그멘테이션(외부 단편화 터짐)**으로 구현됨.
- **MMU**, **페이지 테이블**, **TLB** 3대장이 실시간으로 주소 변환과 권한 컷을 멱살 잡고 때림.

#### 한줄 요약

- 가상 주소로 프로세스들을 격리시키고, MMU와 TLB를 통해 빛의 속도로 주소를 진짜 물리 주소로 번역한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 페이징에서 4KB 타일을 줬는데 1KB만 쓰고 3KB가 텅 비어서 버려지는 공간 낭비 현상이다.
- **외부 단편화(External Fragmentation)**: 세그멘테이션에서 크기가 제멋대로라 여기저기 쪼가리 빈 공간은 많은데, 막상 큰 거 하나 넣으려니 들어갈 구멍이 없는 현상이다.

</details>

```text
[ 가상 메모리 주소 변환 십자포화 아키텍처 ]
               [ MMU & TLB ]
           (하드웨어 초고속 변환기)
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
[ 다단계 페이지 테이블 ]    [ 세그먼트 테이블 ]
  (4KB 타일 매핑 장부)      (크기 제각각인 장부)
         │                       │
         └───────────┬───────────┘
                     ▼
           [ 페이지 폴트 처리기 ]
   (램에 없으면 하드디스크에서 퍼오는 놈)
```

| 구성요소 | 책임 |
|:---|:---|
| **MMU & TLB** | 뇌 비우고 주소 넘기면 캐시(TLB) 뒤져서 빛의 속도로 물리 주소 뱉어내고, 권한 어기면 컷 치는 칩셋 |
| 다단계 페이지 테이블 | 주소 공간 전체 장부를 만들면 너무 크니까, 쓸 부분만 쪼개서 계층으로 만든 메모리 다이어트 장부 |
| 세그먼트 테이블 | 각 세그먼트가 어디서 시작해서 어디까지인지(Base & Limit)를 적어놓고 번역하는 장부 |
| 페이지 폴트 처리기 | "어? 램에 없네?"(폴트) 터지면, 디스크(Swap)로 뛰어가서 데이터 퍼오고 장부 업데이트하는 수습반 |

#### 한줄 요약

- 하드웨어(MMU, TLB)가 1차로 주소 장부를 털고, 못 찾으면 OS의 폴트 처리기가 디스크에서 데이터를 퍼온다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 테이블 워크(Page Table Walk)**: 빠른 주소록(TLB)에 주소가 없어서, MMU가 램에 있는 다단계 페이지 테이블을 1차, 2차 뒤져가며 뺑이 치는 노가다 행위이다.

</details>

```text
[ 가상 주소 변환 및 폴트 처리 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 가상 주소 들이밀기        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. TLB (빠른 주소록) 찔러보기│◀─────────┐
└───────┬──────────────┬───────┘           │
  (TLB 힛)│              │(TLB 미스)         │
        │              ▼                   │
        │    ┌────────────────────┐      │
        │    │ 3. 페이지 테이블 워크│      │
        │    │ (메모리 장부 뒤지기) │      │
        │    └────────────┬───────┘      │
        ▼                 ▼               │
┌──────────────────────────────┐           │
│ 4. 변환 상태 판정 및 접근    │           │
└───────┬──────────────┬───────┘           │
        │              │(램에 없음)        │
(권한위반)│              ▼                   │
        │    ┌────────────────────┐      │
[ 에러 터짐,│    │ 5. 페이지 폴트 처리│      │
  접근 차단]│    │ (디스크에서 퍼옴)  │──────┘
        ▼    └────────────────────┘ (재실행)
[ 진짜 물리 메모리(RAM) 억세스 성공! ]
```

### 동작 원리

1. 가상 주소 인가: CPU가 논리 주소를 뱉음.
2. TLB 찔러보기: MMU가 일단 내부 TLB(캐시)부터 뒤져봄. (힛 나면 바로 4번으로 직행)
3. 페이지 테이블 워크: TLB에 없으면, 램에 짱박힌 다단계 테이블을 뺑이 치며 뒤짐.
4. 변환 및 판정: 주소를 찾았는데 권한(Write 등) 위반이면 즉결 처형, 램에 알박기 중이면 물리 메모리에 꽂힘.
5. 페이지 폴트 처리: 램에 안 보이면 예외 띄우고 디스크 가서 긁어온 뒤 장부 갱신하고 다시 1번부터 돌림.

#### 한줄 요약

- TLB 캐시 $\to$ 메모리 장부 순으로 뒤져서 주소를 찾고, 아예 램에 안 보이면 디스크에서 퍼온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이징된 세그멘테이션(Paged Segmentation)**: 세그멘테이션으로 크게 용도별로 먼저 썰고, 그 안을 다시 페이징 4KB 타일로 잘게 쪼개서 두 기법의 장점만 쏙쏙 빨아먹는 궁극의 혼종 기법이다.

</details>

| 비교 항목 | **페이징** (Paging) | **세그멘테이션** (Segmentation) | **페이징된 세그멘테이션** (Paged Seg) |
|:---|:---|:---|:---|
| 쪼개는 방식 | 무식하게 4KB 똑같은 타일로 썰어버림 | 코드, 데이터, 스택 등 의미 단위로 가변 길이로 썰어냄 | 의미로 먼저 썰고 내부를 다시 타일로 썰어버림 |
| 단편화 (쓰레기 공간) | 타일 안쪽이 남는 **내부 단편화** 터짐 | 타일 밖의 공간이 남는 **외부 단편화** 터짐 | 외부 단편화는 죽이고 내부 단편화만 쥐꼬리만큼 남김 |
| 주소 체계 | 페이지 번호 + 오프셋 (1차원) | 세그먼트 번호 + 오프셋 (2차원) | 세그먼트 번호 $\to$ 페이지 번호 $\to$ 오프셋 |
| 장점 | 외부 쪼가리가 안 생겨서 메모리 낭비가 덜함 | 코드 영역 읽기 전용 박기 같은 보호/공유가 개꿀임 | 보호/공유 챙기면서 단편화 낭비도 억제하는 완성형 |

#### 한줄 요약

- 공간 낭비를 줄이려면 페이징, 보안과 공유가 중요하면 세그멘테이션, 둘 다 챙기려면 페이징된 세그멘테이션이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **휴지 페이지(HugePages)**: 기본 4KB 타일 말고 2MB/1GB짜리 거대한 타일을 박아서, 장부 크기도 줄이고 TLB 캐시 미스도 틀어막는 대용량 튜닝 기술이다.
- **메모리 압축(Memory Compaction / zRAM)**: 램 모자랄 때 디스크 스왑 치면 너무 느리니까, 램 구석탱이에 데이터를 압축해서 쑤셔 박아놓는 발악 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DB가 램을 수십 GB 쓰는데 4KB로 쪼갰더니 TLB 캐시 미스 터지고 속도 개박살 남 | 2MB/1GB짜리 거대한 **휴지 페이지(HugePages)**를 통째로 박아버림 | TLB 커버리지를 떡상시켜서 주소 변환 오버헤드 싹 다 날림 |
| 64비트 OS 주소 공간이 미쳐서 1단계 페이지 테이블 크기가 램을 다 처먹음 | 주소를 쪼개고 쪼개는 **다단계 페이지 테이블(Multi-level)**을 멱살 잡고 도입함 | 안 쓰는 공간의 장부는 아예 안 만들어서 메모리 극적 다이어트 |
| 세그멘테이션 썼더니 빈 공간 쪼가리(**외부 단편화**)가 넘쳐 램이 남아도 할당 불가 | **메모리 압축(Compaction)** 싹 돌려서 영혼까지 끌어모으거나 페이징과 섞음 | 쪼가리들을 싹 밀어서 연속된 대형 가용 메모리 공간 확보 |

#### 한줄 요약

- TLB 미스 오버헤드는 대형 페이지로 막고, 테이블 용량 폭발은 다단계로 막으며, 파편화는 압축으로 민다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상 메모리 아키텍처 선택 기준(Virtual Memory Architecture Criteria)**: 시스템 비트 수나 메모리 사이즈를 보고 장부를 몇 단계로 팔지, 대용량 페이지를 꽂을지 결정하는 설계 잣대이다.

</details>

- **가상 메모리 아키텍처 선택 기준** 원칙에 따라, 범용 OS 환경은 **다단계 페이징**으로 버티고, 대용량 엔터프라이즈 DB는 무조건 **HugePages** 채택 기조 확립함

#### 한줄 요약

- 일반 피씨는 다단계 페이징으로 메모리를 아끼고, 거대 서버는 대형 페이지(HugePages)로 성능을 쥐어짠다.
