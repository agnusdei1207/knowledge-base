## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **성능 테스트 지표(Performance Test Metrics)**: TPS•응답시간•동시 사용자•자원 사용률을 함께 측정해 시스템의 처리 능력, 사용자 지연과 포화 지점을 판단하는 지표 체계이다.
- **초당 거래 수(Transactions Per Second, TPS)**: 시스템이 1초 동안 정상 완료한 업무 거래의 수이다.

</details>

- 정의/개념: TPS•응답시간•동시 사용자•자원 사용률로 처리 능력과 지연•포화 지점을 판단하는 **성능 테스트 지표 체계**
- 배경/필요성: 단일 평균값으로 **꼬리 지연•병목 오판**

#### 한줄 요약
- 처리량과 지연을 함께 봐야 실제 수용량을 앎

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **포화 판정**: 포화 판정은 부하 증가에 따른 TPS, 응답 분위수, 오류율과 자원 사용량을 함께 관찰해 변곡점을 찾는다.
- **응답 분위수(Response Percentile)**: 전체 요청 중 지정 비율이 그 시간 안에 완료되는 지연값이다.
- **생각 시간(Think Time)**: 사용자가 응답을 확인하고 다음 요청을 보내기까지 기다리는 간격이다.
- **리틀의 법칙(Little's Law)**: $N=TPS×(응답시간+Think Time)$ 관계이다.

</details>

![부하 증가에 따른 처리량 포화와 응답 지연 급증](/study/diagrams/load-performance-knee.svg)

> 부하가 포화점에 가까워지면 파란 처리량은 더 늘지 않는 반면 붉은 응답 지연은 급증하는 이론적 예시로, 실제 변곡점은 시스템 측정으로 확인한다.

- **복합 측정**: TPS와 응답 분위수를 함께 관측
- **부하 재현**: Think Time으로 실제 요청 간격 구현
- **포화 판정**: 부하별 오류율•자원 포화도 확인
- **리틀의 법칙** 기반 처리량•동시 사용자 관계 검증

#### 한줄 요약
- TPS가 늘 때 지연•오류가 급증하는 지점을 찾음

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **분석•판정기**: 분석•판정기는 부하 구간별 TPS•지연•오류•자원을 연결해 목표 충족과 병목 지점을 판정한다.
- **부하 모델(Workload Model)**: 사용자 경로•요청 비율•동시 사용자•생각 시간을 정의한 시험 조건이다.
- **부하 생성기(Load Generator)**: 부하 모델에 따라 가상 사용자의 요청을 만들어 시험 대상에 전달하는 도구이다.

</details>

```text
부하 모델
│
부하 생성기
│
시험 대상 시스템
│
지표 수집기
│
분석•판정기
```

선의 의미: 각 선은 사용자 경로•Think Time 조건, 재현 부하, 실제 배포 구조, TPS•지연•오류•자원 측정값과 목표•병목 판정이 서로 대응하는 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 부하 모델 | 사용자 경로•**Think Time 정의** |
| 부하 생성기 | 목표 사용자•**요청률 재현** |
| 시험 대상 시스템 | 실제 배포 구조•**요청 처리** |
| 지표 수집기 | TPS•지연•**오류•자원 수집** |
| 분석•판정기 | 목표 충족•**병목 지점 판정** |


#### 한줄 요약
- 실제 사용자 흐름으로 부하를 만들고 병목을 찾음

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **4. 포화•병목 판정**: 분석기는 부하가 증가할 때 SLO 위반과 먼저 포화되는 자원•구간을 연결해 운영 한계를 정한다.
- **1. 부하 재현**: 사용자 경로와 생각 시간에 따라 단계별 요청 부하를 생성하는 단계이다.
- **2. 처리 지표 전송**: 처리량•응답 시간•오류•자원 사용량을 기록하는 단계이다.
- **3. 집계 지표 전달**: 같은 시간 구간의 측정값을 정규화해 분석기에 보내는 단계이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 응답 시간•오류율 등 서비스 품질이 달성해야 할 측정 기준이다.

</details>

```text
단계별 부하 구간 설정
        |
        v
  1. 부하 재현
        |
        v
2. 처리 지표 전송
        |
        v
3. 집계 지표 전달
        |
        v
4. 포화•병목 판정
        |
        +-- SLO 충족•자원 여유
        |          |
        |          `-- 부하 증가 ---- 다음 구간 반복
        |
        `-- SLO 위반•자원 포화
                   |
                   `-- 안전 운영 용량 확정
```

**동작 원리**

1. **부하 재현**: 사용자 경로•Think Time 기반 부하
2. **처리 지표 전송**: TPS•응답•오류•자원 기록
3. **집계 지표 전달**: 구간별 측정값 정규화
4. **포화•병목 판정**: 목표 위반•포화 구간 연결


#### 한줄 요약
- 임계점 진입 시 오류 발생 여부 검증

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **응답 시간**: 응답 시간은 사용자의 요청 전송부터 전체 응답 수신까지 걸린 시간의 분포로 체감 성능을 나타낸다.
- **동시 사용자(Concurrent User)**: 같은 시점에 시스템과 상호작용하거나 세션을 유지하는 활동 사용자 수이다.
- **초당 거래 수(Transactions Per Second, TPS)**: 완료 거래량 기반 처리 용량

</details>

| 성능 시험 지표 | TPS | 응답 시간 | 동시 사용자 |
|:---|:---|:---|:---|
| 적용 기준 | 처리 용량•**확장 효과 평가** | 체감 성능•**SLO 평가** | 수용 사용자•**세션 평가** |
| 핵심 특징 | 단위 시간 **완료 거래량** | 요청의 **대기시간 분포** | 같은 시점의 **활동 사용자 수** |
| 한계 | 실패 포함•**업무 혼합 왜곡** | 평균의 **꼬리 지연 은폐** | 접속자•**활동자 혼동** |

> 요약: **처리량•지연•오류율** 을 함께 측정해 병목 판정

#### 한줄 요약
- RUM•가상 스크립트 복합 평가 수행

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **꼬리 지연 은폐**: 꼬리 지연 은폐는 평균 응답이 느린 일부 사용자의 p95•p99 지연을 가려 성능 문제를 놓치는 현상이다.
- **95•99백분위 지연(95th/99th Percentile Latency, p95•p99)**: 요청의 95%•99%가 각각 해당 시간 안에 완료됨을 나타내는 꼬리 지연 지표이다.
- **실사용자 모니터링(Real User Monitoring, RUM)**: 실제 사용자의 브라우저•앱에서 체감 지연과 오류를 수집하는 방식이다.
- **콜드•웜 상태(Cold/Warm State)**: 캐시가 비어 있는 초기 조건과 캐시가 채워진 안정 조건이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 운영과 다른 **부하 모델** | 업무량•Think Time **재현** | 시험 대표성 **향상** |
| 평균의 **꼬리 지연 은폐** | p95•p99•**오류율 병행** | 사용자 지연 **가시성** |
| 부하 도구의 **병목 발생** | 분산 생성기•**도구 지표 확인** | 측정 왜곡 **방지** |
| 캐시 상태의 **결과 편향** | Cold•Warm **조건 분리** | 성능 비교 **재현성** |
| 시험과 운영의 **지연 차이** | RUM과 **시험 지표 비교** | 부하 모델 **보정** |

#### 한줄 요약
- 결제는 평균이 빨라도 느린 5%가 기준을 넘으면 실패함



## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **포화점 이하**: p95와 오류율 SLO를 위반하기 전의 포화점 이하에서 안전한 운영 용량을 확정해야 한다.
- **안전 운영 용량(Safe Operating Capacity)**: 꼬리 지연과 오류율 목표를 지키면서 지속 처리할 수 있는 검증된 최대 부하이다.

</details>

- p95•오류 SLO 위반 전 **포화점 이하** 로 운영 용량 확정

#### 한줄 요약
- 처리량만 높고 응답이 느리거나 실패하면 통과가 아님
