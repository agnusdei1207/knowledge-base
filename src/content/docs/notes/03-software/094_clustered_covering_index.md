## 미리 알고가기

- **클러스터드 인덱스 (Clustered Index)**: 키 순서로 실제 행을 배치함
- **커버링 인덱스 (Covering Index)**: 필요한 열을 인덱스에서 모두 제공함
- **리프 페이지 (Leaf Page)**: 인덱스의 최하위 데이터 페이지임
- **포함 컬럼 (Included Column)**: 탐색 없이 결과만 제공하는 열임
- **입출력 (Input/Output, I/O)**: 저장장치의 읽기·쓰기 동작임
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **테이블 재조회(Table Lookup)**: 인덱스에서 찾은 행 위치로 원본 테이블을 다시 읽는 동작임
- **임의 접근(Random Access)**: 연속 순서가 아닌 여러 저장 위치를 직접 찾아 읽는 방식임
- **페이지 분할(Page Split)**: 꽉 찬 페이지에 새 행을 넣기 위해 내용을 둘로 나누는 작업임
- **조각화(Fragmentation)**: 논리적 키 순서와 물리적 페이지 배치가 어긋나 추가 읽기가 생기는 상태임
- **인덱스 재구성(Index Rebuild)**: 인덱스를 다시 만들어 페이지 순서와 여유 공간을 정리하는 작업임

## Ⅰ. 개요

- **정의/개념**: 행 배치와 인덱스 자체 조회를 최적화함
- **배경/필요성**: 범위 탐색·테이블 재조회로 색인 최적화 필요

### 쉽게 이해하기 (학습용)
- 주제순으로 배치하는 것이 클러스터드이고 색인에 답까지 적는 것이 커버링임

## Ⅱ. 특징

- 클러스터드는 범위·정렬 질의의 페이지 읽기를 줄인다.
- 커버링은 인덱스만 읽어 테이블 임의 접근을 줄인다.
- 클러스터드는 키 변경과 페이지 분할에 민감하다.
- 포함 열 증가는 인덱스 페이지·쓰기량을 늘린다.

### 쉽게 이해하기 (학습용)
- 하나는 배치를 바꾸고 다른 하나는 색인만 읽어 답을 얻도록 정보를 넣음

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 클러스터드 키 | 실제 행의 저장 순서를 정함 |
| 리프 페이지 | 키 순서로 실제 데이터 행을 저장함 |
| 포함 컬럼 | 인덱스만으로 제공할 결과 열을 정함 |
| 유지 정책 | 페이지 분할과 조각화 및 재구성을 관리함 |

```text
  클러스터키
      ↓
  리프행저장
      ↓
  조건결과키
      ↓
  포함열결과
```

> 요약: 클러스터드 키는 배치, 포함 열은 조회 결정

### 쉽게 이해하기 (학습용)
- 클러스터드 키는 행의 저장 순서를 정하고 포함 열은 원본 테이블을 다시 읽지 않아도 될 결과 범위를 정함

## Ⅳ. 원리 및 절차 흐름도

```text
  질의식별
      ↓
  배치평가
      ↓
  포함설계
      ↓
  비용검증
```

| 절차 | 설명 |
|:---|:---|
| 질의식별 | 범위와 목록 조회 패턴을 식별함 |
| 배치평가 | 키 분포로 실제 행 배치를 평가함 |
| 포함설계 | 결과에 필요한 최소 컬럼을 포함함 |
| 비용검증 | 읽기 절감과 쓰기 비용을 검증함 |

> 요약: 행 배치와 포함 컬럼으로 읽기와 쓰기 비용을 검증함

### 쉽게 이해하기 (학습용)
- 예상 질의로 읽기 감소를 확인하고 삽입·갱신 시 페이지 분할과 인덱스 크기 증가도 함께 측정함

## Ⅴ. 종류 및 비교

| 비교축 | 클러스터드 인덱스 | 커버링 인덱스 |
|:---|:---|:---|
| 핵심 특징 | 순서에 맞춘 행 배치를 최적화함 | 테이블 재조회 없는 결과를 최적화함 |
| 적용 기준 | 범위와 정렬 조회가 많을 때 적용함 | 고정 컬럼 반복 조회가 많을 때 적용함 |
| 주요 위험 | 페이지 분할과 조각화 비용이 증가함 | 저장 공간과 쓰기 갱신량이 증가함 |

> 요약: 클러스터드는 행 배치를 돕고 커버링은 재조회를 줄임

### 쉽게 이해하기 (학습용)
- 범위 조회는 행 배치를 활용하고 목록 조회는 포함 컬럼을 활용함

## Ⅵ. 실무 사례

1. 주문 이력 시스템은 클러스터드 인덱스로 페이지 분할률을 확인함
2. 목록 조회 시스템은 커버링 인덱스로 재조회 비율을 확인함

### 쉽게 이해하기 (학습용)
- 시간순 주문 이력은 증가 방향 키의 분포와 페이지 분할률을 확인해 범위 조회와 쓰기 비용을 조율함
- 목록 화면의 조건·정렬·출력 열을 인덱스에 포함하면 테이블 재조회 비율과 입출력을 줄일 수 있음

## Ⅶ. 결론

- 행 배치와 재조회 절감 효과를 쓰기 비용과 비교

### 쉽게 이해하기 (학습용)
- 클러스터드와 커버링 인덱스는 질의 패턴이 바뀌면 읽기 이득·분할·크기·갱신 비용을 다시 검증해야 함
