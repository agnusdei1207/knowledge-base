## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **피처 스토어(Feature Store)**: 모델이 사용할 피처 정의와 과거 이력, 실시간 최신값을 같은 기준으로 관리•제공하는 저장 체계이다.
- **피처(Feature)**: 원천 데이터를 모델 입력에 적합하게 선택하거나 변환해 만든 개별 특성 값이다.

</details>

- 정의/개념: **피처 정의•이력•최신값**을 일관되게 제공하는 저장소
- 배경/필요성: 개별 변환 파이프라인으로 **중복•학습 서빙 편향** 발생

#### 한줄 요약
- 같은 재료 가공법을 등록해 과거 훈련 값과 지금 예측 값을 한곳에서 일관되게 제공한다

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **시점 일치 조인(Point-In-Time Join, PIT 조인)**: 각 예측 시점 이전에 알 수 있던 데이터만 결합해 학습 자료의 미래 정보 누수를 막는 방식이다.
- **학습-서빙 편향(Training-Serving Skew)**: 학습과 운영 추론에서 피처 계산식이나 데이터가 달라 모델 입력 분포가 어긋나는 문제이다.
- **피처 계보(Feature Lineage)**: 피처의 원천 데이터•변환식•버전•사용 모델 관계를 추적하는 기록이다.

</details>

- **중앙 피처 정의•버전•계보**로 검색•재사용
- **PIT 조인**으로 학습 데이터의 미래 정보 누수 방지
- **오프라인•온라인 동일 변환**으로 서빙 편향 통제

#### 한줄 요약
- 학습 때 쓴 가공법과 운영 때 쓴 가공법이 같아야 모델이 예상한 입력을 받는다

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **피처 변환기**: 피처 변환기는 레지스트리의 계산식과 스키마로 원천 데이터를 가공해 오프라인 이력과 온라인 최신값을 만든다.
- **피처 레지스트리(Feature Registry)**: 피처 정의•스키마•버전•소유자와 계보를 등록해 검색과 재사용을 지원하는 목록이다.
- **오프라인 저장소(Offline Store)**: 학습과 재현에 사용할 대용량 시점별 피처 이력을 보관하는 저장소이다.
- **온라인 저장소(Online Store)**: 실시간 추론에 사용할 최신 피처를 짧은 지연으로 제공하는 저장소이다.
- **피처 감시기(Feature Monitor)**: 피처의 품질•분포•신선도와 학습-서빙 차이를 관측하는 구성요소이다.

</details>

```text
피처 스토어 구조
      |
      +-- [피처 레지스트리]
      |
      +-- [피처 변환기]
      |         +-- [오프라인 저장소]
      |         +-- [온라인 저장소]
      |
      +-- [피처 감시기]
```

| 구성요소 | 책임 |
|:---|:---|
| 피처 레지스트리 | **정의•소유자•버전•스키마** 관리 |
| 피처 변환기 | 동일 계산식으로 **원천 데이터 가공** |
| 오프라인 저장소 | 훈련에 쓰는 **시점별 이력 피처** 저장 |
| 온라인 저장소 | 추론용 **최신 피처 저지연 제공** |
| 피처 감시기 | **품질•분포•신선도** 관측 |

> 요약: 같은 정의로 이력•최신 피처 생성•감시

#### 한줄 요약
- 한 가공기가 과거용 창고와 실시간용 선반에 값을 나눠 넣고 감시기가 둘의 상태를 확인한다

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 피처 정의 등록**: 계산식•입력 스키마•소유자•버전을 레지스트리에 고정하는 단계이다.
- **2. 단일 정의 기반 변환 실행**: 검증된 계산식으로 원천 데이터를 가공하는 단계이다.
- **3. 시점별 이력 생성**: PIT 조인으로 예측 시점 이전 값만 학습 이력으로 만드는 단계이다.
- **4. 최신 피처 공급**: 동일한 변환 결과의 최신값을 온라인 저장소에 동기화하는 단계이다.
- **5. 품질•신선도•편향 감시**: 저장소 간 차이와 입력 이상을 관찰하는 단계이다.

</details>

```text
1. 피처 정의 등록
      |
      v
2. 단일 정의 기반 변환 실행
      |
      +-- 학습 경로 --> 3. 시점별 이력 생성
      |
      +-- 추론 경로 --> 4. 최신 피처 공급
                              |
                              v
5. 품질•신선도•편향 감시
      |
      +-- 기준 충족 --> 피처 지속 제공
      |
      +-- 기준 미달 --> 원천•정의 교정 후 2단계 반복
```

**동작 원리**

1. **피처 정의 등록**: 계산식•스키마•소유자 고정
2. **단일 정의 기반 변환 실행**: 등록 계산식으로 원천 가공
3. **시점별 이력 생성**: PIT 조인으로 학습 자료 생성
4. **최신 피처 공급**: 같은 계산 결과 온라인 동기화
5. **품질•신선도•편향 감시**: 저장소 차이•입력 이상 관찰

> 요약: 같은 정의로 시점별 이력과 최신 피처 생성

#### 한줄 요약
- 과거 학습에는 그 시점까지 알 수 있던 값만 넣고 같은 계산 결과를 운영 저장소에도 보낸다

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **오프라인 저장소 역할**: 학습•재현용 시점별 대용량 이력 보관
- **온라인 저장소 역할**: 실시간 추론용 최신 피처 제공
- **피처 레지스트리 역할**: 피처 정의•버전•소유권 관리

</details>

| 피처 스토어 영역 | 보관 대상 | 책임 |
|:---|:---|:---|
| **오프라인 저장소** | 사건 시점별 **대용량 피처 이력** | 학습 자료 생성•과거 실험 재현 |
| **온라인 저장소** | 추론 시점의 **최신 피처 값** | 실시간 입력의 저지연 조회 |
| **피처 레지스트리** | 피처 **정의•버전•소유권** | 검색•재사용과 중복 정의 방지 |

> 요약: 이력은 오프라인, 최신값은 온라인, 정의는 레지스트리

#### 한줄 요약
- 과거 값은 큰 창고에서 학습에 쓰고 최신값은 빠른 선반에서 예측에 쓰며 이름표는 레지스트리가 관리한다

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **미래 정보 누수**: 미래 정보 누수는 예측 시점 뒤에 발생한 데이터가 학습 입력에 포함돼 오프라인 평가가 실제보다 높아지는 문제다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 온라인 피처의 지연•가용성•신선도에 대해 달성해야 할 측정 기준이다.
- **서비스 수준 협약(Service Level Agreement, SLA)**: 피처 제공자와 사용자 사이에 품질 수준과 책임을 합의한 약속이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 학습 자료의 **미래 정보 누수** | 사건 시점 기반 **PIT 조인** | 평가 결과 **신뢰성** |
| 학습•추론의 **계산식 차이** | 단일 정의•**변환 코드 재사용** | 서빙 편향 **방지** |
| 온라인 값의 **갱신 지연** | 신선도 SLO•**지연 감시** | 추론 입력 **최신성** |
| 피처의 **소유자 부재** | 소유권•SLA•**폐기 절차 지정** | 품질 책임 **명확화** |

#### 한줄 요약
- 사기 모델은 미래 거래 정보가 학습 입력에 섞이지 않도록 시점을 맞춘다

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **저장소 역할 분리**: 배치 학습은 오프라인 저장소의 시점별 이력을 사용하고 실시간 추론은 온라인 저장소의 최신값을 사용해야 한다.
- **단일 피처 정의(Single Feature Definition)**: 학습과 추론이 같은 변환 규칙을 재사용해 입력 일관성을 유지하는 원칙이다.

</details>

- 학습은 **오프라인**, 추론은 **온라인**, 변환은 단일 정의 재사용

#### 한줄 요약
- 같은 피처 정의를 여러 모델이 재사용하되 과거와 현재 값이 같은 계산법으로 만들어지는지 확인한다
