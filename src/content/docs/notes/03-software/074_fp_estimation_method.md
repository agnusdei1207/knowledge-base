## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Indicative FP / Estimated FP (간이 기능점수 산정법)**: 프로젝트 기획/발주 초기 단계에서 DET/RET/FTR 복잡도를 일일이 조사하지 않고, 5가지 기능 유형별 평균 가중치(Average Weight)를 적용하여 신속하게 예산을 추정하는 기법.
- **Detailed FP (정통 기능점수 산정법)**: 상세 설계서나 완성된 시스템을 대상으로 모든 기능의 DET(필드 수), RET(레코드 수), FTR(참조 파일 수)을 직접 계수하여 복잡도 매트릭스 가중치를 정밀 적용하는 산정 기법.
- **KOSA SW Cost Estimation Guide**: 한국소프트웨어산업협회(KOSA)에서 공공 IT 사업의 발주 및 대정산 시 적용하도록 공식 규정한 기능점수 산정 지침.

</details>

- 정의/개념: 프로젝트 사업 추진 단계별 명세 상세도에 맞춰, 평균 가중치를 적용하는 예산 수립용 **간이법(Estimated FP)** 대 DET/RET/FTR 복잡도를 직접 계수하는 정산용 **정통법(Detailed FP)** 산정 기법
- 배경/필요성: 초기 명세로 정통법을 적용하면 **허위 정밀도•정산 분쟁** 유발

#### 한줄 요약

- 소프트웨어 요구 상세도에 따라 간이법과 정통법을 선택하는 것이 핵심이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Average Weight (평균 가중치)**: 간이법에서 사용하는 평균값 (e.g., ILF=7.5, EIF=5.4, EI=4.0, EO=5.2, EQ=3.9).
- **Phased FP Estimation**: 사업 기획/발주 시점에는 간이법으로 예산 산정 $\rightarrow$ 사업 수행 상세 설계 시점에는 정통법으로 정밀 정산하는 2단계 산정 체계.

</details>

- **Phased Estimation (단계적 산정 체계: 발주 시 간이법 $\rightarrow$ 정산 시 정통법)**
- 평균 가중치(**Average Weight**) 기반 신속성 (**간이법**)
- **DET / RET / FTR** 복잡도 매트릭스 기반 정밀성 (**정통법**)

#### 한줄 요약

- 초기 평균 가중치와 간이값을 정통법으로 재산정하는 절차가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Complexity Matrix (복잡도 매트릭스)**: 정통법에서 DET와 RET/FTR의 개수에 따라 [단순(Low), 보통(Average), 복잡(High)] 3단계 등급을 판정하는 매트릭스 표.

</details>

```text
 [업무 범위] ─── [기능 목록]
      │                 │
 [요구 상세도] ── [평균 가중치]
```

선의 의미: 프로젝트 명세 수준에 따라 간이법(평균 가중치)과 정통법(DET/RET/FTR 매트릭스)이 분기되어 산정되는 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 업무 범위 | 측정 대상과 외부 시스템 경계 확정 |
| 기능 목록 | EI•EO•EQ•ILF•EIF 개수와 근거 관리 |
| 요구 상세도 | 간이법 또는 정통법 선택의 판정 축 제공 |
| 평균 가중치 | 상세 복잡도 부재 시 유형별 추정값 제공 |

#### 한줄 요약

- 업무 범위, 기능 목록, 요구 상세도, 평균 가중치의 산정 구조가 핵심이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IFPUG 평균 가중치 표 (KOSA 기준)**: ILF = 7.5, EIF = 5.4, EI = 4.0, EO = 5.2, EQ = 3.9.

</details>

```text
┌──────────────────────────────┐
│ 사업 추진 단계 확인          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 측정 경계•요구 버전 고정  │
│ 2. 기능 유형•개수 식별       │
│ 3. 요구 상세도 판정          │
│ 4. 선택 산정법 가중치 적용   │
│ 5. 상세화 후 재산정•추적     │
└──────────────┬───────────────┘
               ▼
   [최종 보정계수 적용 및 FP 확정]
```

### 동작 원리

1. **측정 경계•요구 버전 고정**: 산정 대상과 기준 시점 확정.
2. **기능 유형•개수 식별**: 독립 처리와 논리 파일 판정.
3. **요구 상세도 판정**: DET•RET•FTR 계수 가능 여부 확인.
4. **선택 산정법 가중치 적용**: 평균 또는 복잡도 가중치 합산.
5. **상세화 후 재산정•추적**: 간이값과 정통값 차이 설명.

#### 한줄 요약

- 요구 상세도 판정과 선택 산정법 가중치 적용이 핵심이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Detailed Complexity Matrix**: DET 1~19개(Low), 20~50개(Average), 51개 이상(High) 등으로 쪼개어 가중치를 부여하는 정통법의 세부 매트릭스.

</details>

| 기능 유형 | 간이법 평균 가중치 | 정통법 단순(Low) | 정통법 보통(Average) | 정통법 복잡(High) |
|:---|:---|:---|:---|:---|
| **ILF (내부 논리파일)** | **7.5** | 7 | 10 | 15 |
| **EIF (외부 연계파일)** | **5.4** | 5 | 7 | 10 |
| **EI (외부 입력)** | **4.0** | 3 | 4 | 6 |
| **EO (외부 출력)** | **5.2** | 4 | 5 | 7 |
| **EQ (외부 조회)** | **3.9** | 3 | 4 | 6 |

#### 한줄 요약

- 개략 예산에는 간이법, 최종 대가에는 정통법을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **False Precision Trap**: 초기에 명세서도 없으면서 억지로 DET/RET를 예측하여 정통법을 적용했다가 사업비 분쟁을 유발하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기획 단계 정통법 강제로 예산 왜곡 (**False Precision**) | **발주 단계 간이법 명시 $\rightarrow$ 설계 후 정통법 정산 계약**| 분쟁 사전 예방 |
| 간이법 산정 시 기능 개수 뻥튀기 편향 | **독립 처리(Elementary Process) 단위 식별 가이드라인 준수** | 객관적 개수 통제 |
| 정통법 정산 시 변경 요구사항(CR) 불반영 | **기능점수 변경 관리 절차(CR FP Tracking) 구축** | 정당한 SW 대가 수거 |

> 사례: **공공 소프트웨어 사업 발주 시 간이법 적용 및 사업 완료 후 정통법 정산**

#### 한줄 요약

- 측정 경계와 요구 버전 고정 후 간이값을 정통법으로 재산정하는 것이 핵심이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **FP 산정 기법 수립 기준(FP Method Selection Standards)**: IT 사업 수명주기 단계, 설계 산출물 성숙도 및 공공 사업비 정산 규칙에 의거한 체계.

</details>

- 상세 근거가 없으면 **간이법**, DET•RET•FTR 확정 후 **정통법** 선택

#### 한줄 요약

- 요구 상세도에 맞는 기능점수 산정법 선택 기준이 핵심이다.
