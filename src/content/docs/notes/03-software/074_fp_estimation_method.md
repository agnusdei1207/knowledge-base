## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **소프트웨어(Software, SW)**: 컴퓨터가 기능을 수행하도록 만든 프로그램•데이터•관련 산출물의 집합이다.
- **기능점수(Function Point, FP)**: 사용자 기능의 논리 규모를 측정하는 단위이다.
- **간이법(Simplified Method)**: 기능 유형별 평균 가중치로 FP를 추정하는 방법이다.
- **정통법(Detailed Method)**: 복잡도별 가중치로 FP를 계산하는 방법이다.
- **정통법 산정 불가**: DET•RET•FTR 정보가 부족해 기능별 복잡도를 상세 판정할 수 없는 상태이다.

</details>

- 정의/개념: **기능점수**를 평균 가중치로 추정하는 **간이법**과 상세 복잡도 가중치로 계산하는 **정통법**이다.
- 배경/필요성: 불완전한 초기 요구에는 DET•RET•FTR 정보가 부족해 **정통법 산정 불가** 상태가 된다.

#### 한줄 요약

- **소프트웨어** 요구 상세도에 따라 **간이법**과 **정통법**을 선택하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **간이값을 정통법으로 재산정**: 요구가 구체화되면 초기 추정치를 상세 근거로 다시 계산하는 절차이다.

</details>

- **간이법**은 평균 가중치로 초기 규모를 신속하게 산정한다.
- **정통법**은 DET•RET•FTR로 복잡도를 판정한다.
- 요구 구체화 시 **간이값을 정통법으로 재산정**이 핵심이다.

#### 한줄 요약

- 초기 평균 가중치와 **간이값을 정통법으로 재산정**하는 절차가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **업무 범위(Business Scope)**: 기능점수 측정에 포함할 업무 경계이다.
- **기능 목록(Function List)**: 측정 대상으로 식별한 사용자 기능 집합이다.
- **요구 상세도(Requirement Detail)**: 기능 복잡도를 판정할 수 있는 요구 구체성이다.
- **평균 가중치**: 간이법에서 기능 유형별로 동일하게 적용하는 대표 복잡도 값이다.
- **데이터 요소 유형(Data Element Type, DET)**: 사용자가 식별하는 필드 유형이다.
- **레코드 요소 유형(Record Element Type, RET)**: 논리 파일의 하위 레코드 그룹 유형이다.
- **참조 파일 유형(File Type Referenced, FTR)**: 트랜잭션이 참조하거나 유지하는 파일 유형이다.

</details>

```text
                   [간이법 산정]
                    /          \
[입력 요구사항]                  [검증 기준]
                    \          /
                   [정통법 산정]
```

선의 의미: 입력 요구사항의 상세도에 따라 간이법 산정 또는 정통법 산정이 적용되며, 두 산정 결과는 동일한 검증 기준으로 누락•중복과 근거를 확인한다.

| 구성요소 | 책임 |
|:---|:---|
| 입력 요구사항 | **업무 범위**, **기능 목록**, **요구 상세도** 제공 |
| 간이법 산정 | 기능 유형별 **평균 가중치** 적용 |
| 정통법 산정 | **데이터 요소 유형**, **레코드 요소 유형**, **참조 파일 유형**으로 복잡도 판정 |
| 검증 기준 | 기능 누락•중복•산정 근거 검토 |

#### 한줄 요약

- **업무 범위**, **기능 목록**, **요구 상세도**, **평균 가중치**의 산정 구조가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **외부 입력(External Input, EI)**: 외부에서 내부 논리 파일을 변경하는 기능이다.
- **외부 출력(External Output, EO)**: 계산을 포함해 외부로 데이터를 내보내는 기능이다.
- **외부 조회(External Inquiry, EQ)**: 계산 없이 데이터를 조회하는 기능이다.
- **내부 논리 파일(Internal Logical File, ILF)**: 측정 대상이 유지하는 논리 데이터이다.
- **외부 연계 파일(External Interface File, EIF)**: 외부가 유지하고 측정 대상이 참조하는 데이터이다.
- **산정법(Estimation Method)**: 기능점수 계산에 적용한 방법이다.
- **판정 근거(Estimation Rationale)**: 기능 분류와 가중치를 선택한 이유이다.
- **기능점수 기준선**: 요구 버전•범위•규칙을 고정해 변경 전후 규모를 비교하는 기준이다.
- **미조정 기능점수(Unadjusted Function Point, UFP)**: 다섯 기능 유형의 개수와 복잡도 가중치를 합산한 조정 전 기능점수이다.
- **다섯 기능 유형 식별**: 사용자 기능을 EI•EO•EQ•ILF•EIF로 중복 없이 분류하는 동작이다.
- **요구 상세도 판정**: DET•RET•FTR 근거의 확보 여부로 간이법과 정통법을 고르는 동작이다.
- **선택 산정법 가중치 적용**: 초기 요구에는 평균값, 상세 요구에는 복잡도별 값을 적용하는 동작이다.
- **UFP 합산**: 유형별 기능 개수와 적용 가중치를 곱해 미조정 기능점수를 계산하는 동작이다.
- **근거 검토•기준선 확정**: 누락•중복•산정법•규칙 판본을 확인해 공식 규모를 승인하는 동작이다.

</details>

```text
[산정 목적•범위•요구 버전]
           |
           v
+-----------------------------+
| 1. 다섯 기능 유형 식별     |
+-----------------------------+
           |
           v
+-----------------------------+
| 2. 요구 상세도 판정        |
+-----------------------------+
           |
     +-----+-----+
     | 초기 요구 | 상세 요구
     v           v
[간이 평균값] [DET•RET•FTR 복잡도]
     |           |
     +-----+-----+
           |
           v
+-----------------------------+
| 3. 선택 산정법 가중치 적용 |
+-----------------------------+
           |
           v
+-----------------------------+
| 4. UFP 합산                |
+-----------------------------+
           |
           v
+-----------------------------+
| 5. 근거 검토•기준선 확정  |
+-----------------------------+
```

### 동작 원리

1. **다섯 기능 유형 식별**: **외부 입력**, **외부 출력**, **외부 조회**, **내부 논리 파일**, **외부 연계 파일**을 분류한다.
2. **요구 상세도 판정**: 간이법•정통법 **산정법**을 선택한다.
3. **선택 산정법 가중치 적용**: 평균값•상세값을 반영한다.
4. **UFP 합산**: **미조정 기능점수**를 계산한다.
5. **근거 검토•기준선 확정**: **판정 근거**를 검토해 **기능점수 기준선**을 확정한다.

> 요약: 요구 상세도에 맞는 가중치를 선택하고 판정 근거와 함께 기능점수를 확정한다.

#### 한줄 요약

- **요구 상세도 판정**과 **선택 산정법 가중치 적용**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **개략 예산**: 초기 요구의 기능 개수와 평균 가중치로 빠르게 추정한 비용 범위이다.
- **최종 대가**: 상세 요구와 기능별 복잡도를 근거로 계약 종료 시 확정하는 비용이다.
- **상세 복잡도 가중치**: DET•RET•FTR 조합으로 기능마다 판정한 정통법의 값이다.

</details>

| 기능점수 산정법 | 간이법 | 정통법 |
|:---|:---|:---|
| 적용 기준 | 기획•발주의 **개략 예산** 산정 | 설계•종료의 **최종 대가** 정산 |
| 핵심 특징 | 기능 유형별 **평균 가중치** | 요소별 **상세 복잡도 가중치** |
| 한계 | 요구 누락과 범위 변동에 민감 | 상세 분류 오류와 산정 비용 증가 |

> 요약: 간이법은 평균 가중치이고 정통법은 상세 복잡도를 적용하는 것이 핵심이다.

#### 한줄 요약

- **개략 예산**에는 **간이법**, **최종 대가**에는 **정통법**을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **가짜 정밀도(False Precision)**: 불충분한 입력으로 계산한 값을 실제보다 정확해 보이게 제시하는 오류이다.
- **측정 경계(Measurement Boundary)**: 산정값 비교를 위해 고정할 시스템 안팎의 기준이다.
- **요구 버전(Requirement Version)**: 기능점수 산정에 사용한 요구의 판본이다.
- **제외 범위(Exclusion Scope)**: 기능점수 산정에서 빼기로 합의한 대상이다.
- **규칙 판본(Rule Version)**: 산정에 사용한 가중치 규칙의 버전이다.
- **사용자 목적(User Goal)**: 사용자가 인식하는 완결된 업무 목표이다.
- **독립 처리(Elementary Process)**: 화면과 외부 인터페이스 구현에 무관한 최소 기능 단위이다.
- **추가 증감(Addition Delta)**: 새 기능이 점수에 더한 값이다.
- **삭제 증감(Deletion Delta)**: 제거 기능이 점수에서 빠진 값이다.
- **복잡도 증감(Complexity Delta)**: 복잡도 등급 변화가 점수에 미친 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 초기 요구에 정통법을 적용해 **가짜 정밀도** 발생 | 초기에는 **간이법**, 요구 확정 후 **간이값을 정통법으로 재산정** | 가짜 정밀도 방지 |
| 시스템 경계•요구 버전 변경으로 산정값 비교 불가 | **측정 경계**, **요구 버전**, **제외 범위** 기준선 고정 | 산정값 비교 가능성 확보 |
| 같은 기능을 화면•외부 인터페이스별로 중복 계수 | **사용자 목적**과 **독립 처리**로 검토 | 논리 기능 왜곡 방지 |
| 간이•정통 가중치와 다른 규칙 판본을 혼용 | **산정법**, **규칙 판본**, **판정 근거** 명시 | 산정 규칙 일관성 확보 |
| 재산정 총점만 제시해 변화 원인을 설명하지 못함 | **추가 증감**, **삭제 증감**, **복잡도 증감** 추적 | 재산정 변화 원인 설명 |

> 적용 사례: 공공 소프트웨어 사업은 초기 간이법 후 상세 요구로 정통법 재산정

#### 한줄 요약

- **측정 경계**와 **요구 버전** 고정 후 **간이값을 정통법으로 재산정**하는 것이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **기능점수 산정법 선택 기준**: 요구 상세도와 산정 목적이 초기 예산인지 최종 정산인지에 따라 간이법과 정통법 중 하나를 정하는 기준이다.

</details>

- **기능점수 산정법 선택 기준**에 따라 초기 **개략 예산**은 **간이법**, 상세 **최종 대가**는 **정통법**을 선택한다.

#### 한줄 요약

- 요구 상세도에 맞는 **기능점수 산정법 선택 기준**이 핵심이다.
