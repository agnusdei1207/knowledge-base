## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **간이법 및 정통법(Estimated FP & Detailed FP)**: 프로젝트 기획 단계에서 5대 기능 유형별 평균 가중치를 적용하는 간이법과 상세 설계 단계에서 DET/RET를 정밀 계수하는 정통법.
- **허위 정밀도 오차 및 대금 정산 분쟁(False Precision & Dispute)**: 초기 요구사항이 모호함에도 무리하게 정통법을 적용하여 예산 왜곡이 발생하고 준공 시 대금 분쟁으로 이어지는 위험.

</details>

- 정의/개념: 소프트웨어 개발 단계별 요구명세 완성도에 따라 **평균 가중치를 적용하는 사전 예산용 간이법과 DET/RET 정밀 계수 기반 사후 정산용 정통법**으로 나뉘는 규모 측정 기법
- 배경/필요성: 사업 초기 상세 설계 부재 상황에서 정통법 강행 시 발생하는 **허위 정밀도 오차 및 발주자와 수주자 간 대금 정산 분쟁** 직면

#### 한줄 요약

- 프로젝트 생명주기 단계별 명세 상세도에 따라 간이법과 정통법을 단계적으로 적용하여 공정한 사업 대가를 산정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **평균 가중치(Average Weight)**: IFPUG/KOSA 통계에 기반하여 산출된 5대 기능 유형별 표준 가중치 (ILF 7.5, EIF 5.4, EI 4.0, EO 5.2, EQ 3.9).
- **2단계 산정 체계(Phased Estimation)**: 기획/발주 시점에는 간이법으로 예산을 편성하고 상세 설계 완료 후 정통법으로 정밀 정산하는 프레임워크.

</details>

- 사업 초기 예산 확보를 위한 **간이법(Estimated FP) 기반 신속 산정**
- 상세 설계서 확정 후 정산용 **정통법(Detailed FP) 기반 정밀 계수**
- 기획 시점 간이법 발주 후 설계 완료 시점 정통법 정산의 **단계적 연계 체계**

#### 한줄 요약

- 기획 단계에서는 평균 가중치로 신속하게 예산을 확보하고 설계 완료 후에는 정밀 계수로 정산

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **복잡도 매트릭스(Complexity Matrix)**: 정통법에서 DET(필드 수)와 RET/FTR(레코드/참조파일 수)의 교차 테이블을 통해 단순/보통/복잡 등급을 판정하는 매트릭스.

</details>

```text
[ 기능점수 간이법 및 정통법 산정 아키텍처 ]

                      [ 소프트웨어 요구사항 명세서 ]
                                     │
                 ┌───────────────────┴───────────────────┐
                 │ (기획/발주 단계)                      │ (상세설계/정산 단계)
                 ▼                                       ▼
     [ 간이 기능점수 산정법 ]                [ 정통 기능점수 산정법 ]
     - 5대 기능 유형 개수 식별                - 5대 기능 유형 개수 식별
     - 표준 평균 가중치 적용                 - DET, RET, FTR 정밀 계수
       (ILF 7.5, EI 4.0 등)                  - 복잡도 매트릭스(Low/Avg/High) 대입
                 │                                       │
                 ▼                                       ▼
     [ 사전 예산 편성용 FP ] ───(정산 연계)───► [ 최종 사업 대정산용 FP ]
```

선의 의미: 프로젝트 추진 단계(기획 vs 상세설계)에 따라 간이법과 정통법으로 분기 적용되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 간이법 (Estimated FP) | 기획/발주 단계에서 **5대 기능 유형별 표준 평균 가중치(Average Weight) 적용** |
| 정통법 (Detailed FP) | 상세 설계/정산 단계에서 **DET, RET, FTR을 정밀 계수하여 복잡도 매트릭스 대입** |
| 복잡도 매트릭스 | 필드 수와 참조 파일 수에 따라 **단순, 보통, 복잡 등급을 판정** |
| 평균 가중치 (Average Weight) | 기획 단계 상세 데이터 부재 시 **IFPUG/KOSA 표준 통계 가중치 제공** |

#### 한줄 요약

- 간이법은 평균 가중치로 신속하게 계산하고 정통법은 복잡도 매트릭스로 정밀 계수

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **단위 프로세스(Elementary Process)**: 트랜잭션 기능(EI/EO/EQ) 식별의 기본 단위로, 사용자에게 의미가 있고 자체적으로 완결되는 최소 작업 단위.

</details>

```text
[ 간이법/정통법 단계적 산정 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 측정 경계 및 요구사항 버전 고정    │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 기능 유형 식별: 5대 기능 도출       │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 명세 상세도 판정: 간이법 vs 정통법  │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 가중치 대입: 평균값 또는 DET 계수   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. UFP 합산 및 최종 개발비 산출       │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 측정 경계 및 요구사항 고정: 사업 범위와 기능 명세서의 베이스라인 버전을 확정.
2. 기능 유형 식별: 사용자 관점에서 5대 기능 유형(ILF, EIF, EI, EO, EQ)의 목록을 추출.
3. 명세 상세도 판정: DET/RET를 계수할 수 있는 상세 설계서 존재 여부에 따라 산정 방식(간이법 vs 정통법) 선택.
4. 가중치 대입: 간이법은 평균 가중치(ILF 7.5 등)를 대입하고, 정통법은 DET/RET 계수 후 매트릭스 가중치를 대입.
5. UFP 합산 및 개발비 산출: 미조정 기능점수를 계산하고 보정계수를 곱하여 최종 사업비를 산출.

#### 한줄 요약

- 경계 고정 $\to$ 기능 식별 $\to$ 상세도 판정 $\to$ 가중치 대입 $\to$ 대가 산출의 5단계 절차로 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **산정 오차율(Estimation Error Rate)**: 사업 초기 간이법 추정치와 상세 설계 후 정통법 정산치 간의 편차 비율.

</details>

| 구분 | 간이 기능점수 산정법 (Estimated FP) | 정통 기능점수 산정법 (Detailed FP) |
|:---|:---|:---|
| **적용 기준** | 사업 기획, 예산 수립, 발주 공고 단계 | 상세 설계 완료 후 또는 최종 대금 정산 단계 |
| **핵심 특징** | **기능 유형별 표준 평균 가중치(Average Weight) 적용** | **실제 DET, RET, FTR 계수 후 복잡도 매트릭스 대입** |
| **한계** | 상세 명세 부재로 인한 개략적 오차 존재 | 상세 분석에 따른 많은 시간과 전문 인력 공수 소요 |

#### 한줄 요약

- 기획 단계에서는 간이법으로 신속하게 예산을 확보하고, 설계 완료 후에는 정통법으로 정확한 대가를 정산

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **False Precision Trap**: 요구사항이 불명확한 초기에 억지로 DET/RET를 추정하여 정통법을 적용했다가 사업비 왜곡과 분쟁을 유발하는 안티패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 초기 단계 무리한 정통법 적용으로 예산 왜곡 (False Precision) | **기획/발주 시 간이법 적용 명시 후 설계 완료 시 정통법 정산 계약** | 사업비 왜곡 방지 및 예산 집행 적시성 확보 |
| 간이법 적용 시 트랜잭션 기능 개수 과다 산정 편향 | **IFPUG 표준 단위 프로세스(Elementary Process) 식별 원칙 준수** | 기능 개수 뻥튀기 억제 및 객관성 확보 |
| 사업 진행 중 요구사항 변경(CR)에 따른 기능점수 누락 | **요구사항 변경 관리(CR)와 연동된 FP 변경 추적 대장 운용** | 추가 과업에 대한 정당한 대가 정산 보장 |

#### 한줄 요약

- 간이-정통 2단계 계약, 단위 프로세스 준수, 변경 관리 연동으로 분쟁 없는 공정한 대가 산정을 실현

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **단계적 대가 정산(Phased Cost Settlement)**: 소프트웨어 개발 생명주기의 성숙도에 맞추어 계약 금액을 점진적으로 확정하는 선진 발주 체계.

</details>

- **간이법과 정통법**은 상호 배타적인 기법이 아닌 개발 생명주기 단계에 따른 상호 보완적 도구이며, 발주 시 간이법으로 예산을 확보하고 설계 후 정통법으로 정산하는 2단계 체계를 확립해야 함

#### 한줄 요약

- 명세 성숙도에 부합하는 산정 방식을 단계적으로 적용하여 공공 및 민간 IT 사업의 신뢰성을 확보
