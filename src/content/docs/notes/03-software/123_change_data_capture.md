## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **변경 데이터 캡처(Change Data Capture, CDC)**: 원천 데이터의 삽입•수정•삭제를 식별해 변경 이벤트로 추출하는 증분 수집 기법이다.

</details>

- 정의/개념: 원천 데이터의 삽입•수정•삭제를 변경 이벤트로 추출하는 **증분 수집 기법**이다.
- 배경/필요성: 주기적 전체 복사는 데이터 증가 시 **원천 부하•동기화 지연** 확대가 발생한다.

#### 한줄 요약
- 원본 장부를 매번 복사하지 않고 바뀐 부분만 찾아 다른 시스템에 전달하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **초기 스냅숏**: 기존 전체 상태와 후속 변경 로그 사이에 누락 없는 시작 경계를 만드는 과정이다.
- **원천 오프셋**: 원천 변경 로그에서 커넥터가 안전하게 발행•확정한 마지막 위치이다.
- **스키마 이력**: 각 변경 이벤트가 발생한 시점의 테이블 구조와 열 의미를 보존한 기록이다.

</details>

- 변경 로그 시작 위치와 연속성을 보장하는 **초기 스냅숏**이 핵심이다.
- 확정된 **원천 오프셋** 부터 변경 로그 재생이 핵심이다.
- 시점별 **스키마 이력**으로 과거 변경값 해석이 핵심이다.

#### 한줄 요약
- CDC는 첫 전체 복사와 이후 로그 사이의 빈 구간을 없애고 마지막 확정 위치부터 안전하게 다시 읽어야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **오프셋**: 재시작할 원천 로그 위치를 보존하는 값이다.
- **스키마 이력**: 시점별 테이블 구조를 보존하는 기록이다.
- **CDC 커넥터**: 원천 변경 로그를 읽어 표준 변경 이벤트로 변환하는 구성요소이다.
- **데이터베이스(Database, DB)**: 구조화된 원천 데이터를 저장하고 관리하는 체계이다.
- **변경 로그**: 커밋된 삽입•수정•삭제의 순서와 값을 제공하는 기록이다.
- **이벤트 브로커**: 변경 이벤트를 파티션 순서로 보존하고 독립 소비와 재생을 제공하는 구성요소이다.
- **싱크 커넥터**: 대상 시스템에 변경 이벤트를 멱등하게 적용하는 구성요소이다.

</details>

```text
[CDC 처리 체계]
       |
       +-- [원천 DB•변경 로그]
       |
       +-- [CDC 커넥터]
       |          |
       |          +-- [오프셋•스키마 이력]
       |
       +-- [이벤트 브로커]
                  |
                  +-- [싱크 커넥터]
```

선의 의미: 원천 DB•변경 로그와 CDC 커넥터의 선은 커밋된 삽입•수정•삭제 기록 제공 관계, CDC 커넥터와 오프셋•스키마 이력의 선은 재시작 위치•시점별 구조 보존 관계, CDC 커넥터와 이벤트 브로커의 선은 표준 변경 이벤트 발행 관계, 이벤트 브로커와 싱크 커넥터의 선은 순서•재생 가능한 이벤트의 대상 시스템 반영 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 원천 DB•변경 로그 | 커밋된 **삽입•수정•삭제** 기록 제공 |
| CDC 커넥터 | 원천 로그를 **변경 이벤트**로 변환 |
| 오프셋•스키마 이력 | **재시작 위치•시점별 구조** 보존 |
| 이벤트 브로커 | 변경 이벤트의 **순서•재생** 보장 |
| 싱크 커넥터 | 대상 시스템에 **멱등 반영** |

#### 한줄 요약

- 원본 장부, 일지 판독기, 책갈피, 전달 일지, 대상 반영기로 구성된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **스냅숏 기준 위치 고정**: 초기 상태와 후속 로그를 누락 없이 이을 원천 위치를 확정하는 단계이다.
- **초기 상태 이벤트 발행**: 기존 행을 대상 시스템의 기준 상태로 만드는 단계이다.
- **커밋 순서 변경 로그 판독**: 트랜잭션 확정 순서대로 삽입•수정•삭제를 읽는 단계이다.
- **표준 변경 이벤트 변환**: 키•전후 값•스키마•원천 위치를 표준 형식으로 만드는 단계이다.
- **변경 이벤트 보존**: 변환한 이벤트를 파티션 순서로 저장해 재생 가능하게 하는 단계이다.

</details>

```text
CDC 시작
   |
   v
초기 상태 존재 여부
   |
   +-- 없음 --> 1. 스냅숏 기준 위치 고정
   |                         |
   |                         v
   |                2. 초기 상태 이벤트 발행
   |                         |
   +-------------------------+
   |
   v
3. 커밋 순서 변경 로그 판독
   |
   v
4. 표준 변경 이벤트 변환
   |
   v
5. 변경 이벤트 보존
   |
   +-- 대상 시스템에 멱등 반영
   |
   +-- 확정 원천 오프셋 기록
```

**동작 원리**

- **1. 스냅숏 기준 위치 고정**: 초기 행과 이후 로그를 잇는 원천 위치 확정이다.
- **2. 초기 상태 이벤트 발행**: 기존 행을 대상 시스템의 기준 상태로 변환한다.
- **3. 커밋 순서 변경 로그 판독**: 커밋 순서대로 삽입•수정•삭제 판독이다.
- **4. 표준 변경 이벤트 변환**: 키•변경값•스키마•원천 위치 결합한다.
- **5. 변경 이벤트 보존**: 파티션 순서로 저장해 독립 소비•재생을 제공한다.

#### 한줄 요약

- 첫 전체 복사의 끝과 변경 일지의 시작을 맞추고 마지막 발행 위치를 책갈피로 남긴다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **로그 기반 변경 데이터 캡처(Log-based Change Data Capture, Log-based CDC)**: 원천 변경 로그의 커밋 순서를 판독해 변경 이벤트를 추출하는 방식이다.
- **트리거 기반 변경 데이터 캡처(Trigger-based Change Data Capture, Trigger-based CDC)**: 데이터베이스 트리거가 변경 내용을 별도 표에 기록하도록 하는 방식이다.
- **쿼리 기반 변경 데이터 캡처(Query-based Change Data Capture, Query-based CDC)**: 수정 시각이나 증가 키로 원천을 주기 조회해 변경분을 찾는 방식이다.

</details>

| CDC 방식 | 로그 기반 CDC | 트리거 기반 CDC | 쿼리 기반 CDC |
|:---|:---|:---|:---|
| 적용 기준 | 원천 **변경 로그 접근**가능 | 원천에 **트리거 설치**가능 | 변경량이 적고 **주기 조회** 허용 |
| 핵심 특징 | 복구 로그의 **커밋 순서** 판독 | 트리거가 **변경표** 자동 기록 | 수정 시각 기준 **증분 쿼리** |
| 한계 | 로그 만료•**제품 종속성** | 원천 쓰기 지연•**트리거 누락** | 조회 경계 경쟁•**삭제 누락** |

#### 한줄 요약

- 변경 일지를 읽는 방식이 가장 자연스럽지만 권한이 없으면 표식이나 주기 조회를 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **오래된 행 잔존**: 원천에서 지운 레코드가 대상 시스템에는 계속 남는 문제이다.
- **기준 위치 고정**: 스냅숏과 후속 로그를 잇는 원천 위치를 확정하는 통제이다.
- **변경 버퍼**: 스냅숏 중 발생한 변경을 임시 보관하는 공간이다.
- **대사 검증**: 초기 복사와 후속 로그의 누락•중복을 비교하는 통제이다.
- **로그 보존 기간**: 커넥터의 최대 중단 시간보다 길게 유지해 기존 오프셋에서 재생할 수 있게 하는 기간이다.
- **원천 버전 비교**: 같은 업무 키의 이벤트가 역순 도착해도 더 최신 변경만 반영하도록 버전을 대조하는 방식이다.
- **툼스톤(Tombstone)**: 삭제된 키를 나타내는 표식이다.
- **삭제 이벤트**: 원천 삭제 사실을 대상에 전달하는 사건이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스냅숏 중 변경 로그를 놓치면 **초기 상태 누락** 발생 | 기준 위치 고정과 **버퍼•대사 검증** | 초기•후속 변경의 **연속성** 보장 |
| 중단 시간이 로그 보존 기간보다 길면 **재시작 위치 만료** | 최대 중단 시간보다 긴 **로그 보존 기간** 설정 | 전체 재수집 없는 **로그 재생** 보장 |
| 같은 키의 변경 순서가 뒤집히면 **과거 값 재반영** | 업무 키별 **원천 버전 비교** | 최신 상태의 **순서 일관성** 유지 |
| 삭제 이벤트가 빠지면 대상에 **오래된 행 잔존** | **툼스톤•삭제 이벤트** 전달과 원천 대사 | 대상 시스템의 **삭제 상태** 동기화 |

#### 한줄 요약

- 같은 원본 키와 최신 변경 번호로 검색 문서를 고치고 삭제까지 전달해야 오래된 결과가 남지 않는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **선택 기준**: 변경 로그 접근 권한과 원천 변경량의 비교 축이다.

</details>

- 로그 접근 가능 시 **로그 기반 CDC**, 불가 시 **트리거•쿼리 방식**을 선택한다.

#### 한줄 요약

- 첫 복사와 변경 일지의 경계, 마지막 책갈피, 삭제와 구조 변경까지 맞아야 한다.
