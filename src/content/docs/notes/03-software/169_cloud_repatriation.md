## 미리 알고가기

- **클라우드 회귀**: 퍼블릭 클라우드의 자원을 자체 환경으로 다시 이전하는 전략임
- **총 소유 비용 TCO(티씨오, Total Cost of Ownership)**: 영어 세 낱말의 첫 글자를 쓴 표기로 인프라의 구축·운영·이전 비용을 합산해 회귀 타당성을 판단함
- **데이터 중력**: 데이터 규모가 커질수록 처리 시스템을 데이터 주변에 두려는 제약임
- **출구 계획**: 데이터 반출, 호환 형식 등 안전하게 클라우드를 벗어나는 사전 계획임
- **워크로드**: 애플리케이션과 이를 실행하는 데이터·연산 자원의 묶음임
- **응용 프로그래밍 인터페이스 API(에이피아이, Application Programming Interface)**: 영어 핵심어의 첫 글자를 쓴 약어로 시스템 기능을 다른 프로그램이 호출하는 규격이며 이전 시 대체 범위를 판단함
- **롤백**: 전환 실패 시 기존 정상 환경으로 되돌리는 복구임
- **기계 학습 ML(엠엘, Machine Learning) 추론·그래픽 처리 장치 GPU(지피유, Graphics Processing Unit)**: 각 영어 낱말의 첫 글자를 쓴 약어로 ML 추론은 학습 모델로 결과를 예측하고 GPU는 이를 병렬 처리해 회귀 대상의 비용·지연을 판단함


## Ⅰ. 개요

- 정의/개념: 퍼블릭 클라우드 자원을 자체 환경으로 이전
- **배경/필요성**: 지속 부하 비용·종속 증가로 회귀 판단 필요

### 쉽게 이해하기 (학습용)
- 퍼블릭 클라우드 자원을 자체 환경으로 다시 배치함

## Ⅱ. 특징

- 워크로드별 운영 부하와 데이터 요구를 분석한다.
- 현재 사용료와 자체 인프라 TCO를 비교한다.
- 서비스 대체 범위로 이전 난이도를 산정한다.
- 데이터 동기화와 전환으로 무결성을 확인한다.
- 출구 계획으로 반출 비용을 검증한다.

### 쉽게 이해하기 (학습용)
- 단순한 사용료 외에 인프라 구축과 이전 비용을 계산

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    A[후보 평가] --> B[TCO 분석]
    B --> C[목표 환경]
    C --> D[이식 계층]
    D --> E[전환 통제]
```

| 설계 요소 | 설명 |
|:---|:---|
| 후보평가 | 사용량과 데이터 흐름 및 규제를 분석함 |
| TCO분석 | 자체 인프라 비용과 이전 위험을 비교함 |
| 목표환경 | 자원 용량과 복구 방식을 설계함 |
| 이식계층 | 개방형 형식과 대체 API를 적용함 |
| 전환통제 | 데이터 동기화와 무결성을 검증함 |

> 요약: 자원 타당성 분석 후 환경을 구축하여 전환함

### 쉽게 이해하기 (학습용)
- 적합한 대상을 선정하고 비용을 계산한 후 이전을 시작함

## Ⅳ. 원리 및 절차 흐름도

| 절차 | 설명 |
|:---|:---|
| 후보검증 | TCO와 자체 운영 역량으로 후보 판정함 |
| 환경구축 | 보안과 복구 기준 충족 시스템 구성함 |
| 데이터동기 | 복제와 변경분 반영해 정합성 확인함 |
| 점진전환 | 일부 트래픽을 넘겨 롤백 조건 확인함 |
| 완료폐기 | 서비스 이전 확인 후 기존 종료함 |
> 요약: 타당성을 검증한 뒤 트래픽을 옮기고 기존 환경을 폐기함

### 쉽게 이해하기 (학습용)
- 비용 가치를 계산해 데이터와 트래픽을 목표 환경으로 이전함

## Ⅴ. 종류 및 비교

| 판단 기준 | 클라우드 유지 | 클라우드 회귀 |
|:---|:---|:---|
| 핵심 특징 | 탄력적 확장과 자원 단위 비용 | 지속 부하 자체 인프라 처리 |
| 적용 기준 | 변동 부하·관리형 기능 활용 | 안정 부하·비용·통제 회수 |
| 주요 위험 | 비용 변동·공급자 종속 | 이전 중단·운영 역량 부족 |

> 요약: TCO와 통제 요구 타당 시 회귀를 결정함

### 쉽게 이해하기 (학습용)
- 수요 변동이 크면 클라우드를 쓰고 지속 부하는 회귀를 선택함

## Ⅵ. 실무 사례

1. ML 추론은 사설 GPU로 이전해 지연을 줄임

### 쉽게 이해하기 (학습용)
- ML 추론은 GPU 비용과 처리 지연을 비교함

## Ⅶ. 결론

- 클라우드 운영비와 통제 한계를 개선하기 위해 **워크로드 TCO·성능 예측성·데이터 이동비·운영 역량·이전 중단 위험**을 검토하고, 회귀 편익이 전환 비용보다 클 때만 온프레미스로 이전한다

### 쉽게 이해하기 (학습용)
- 싼 사용료만 보지 말고 이전·운영 비용까지 더함
