## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISMP (Information System Master Plan)**: 선정된 정보화 사업의 요구•목표•규모•발주 기준을 구체화하는 실행 계획
- **RFP (Request for Proposal)**: 요구사항과 계약•평가 조건을 제시하는 제안요청서

</details>

- 정의/개념: 구축 사업을 요구•목표•규모•RFP로 구체화하는 **ISMP**
- 배경/필요성: 전략 과제만으로는 **구축 범위•예산•검수 기준** 확정 불가

#### 한줄 요약

- 전략 과제를 발주 가능한 **사업 기준선**으로 구체화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **BPR (Business Process Reengineering)**: 목표 업무 달성을 위해 기존 절차를 근본적으로 재설계하는 기법

</details>

- **사업 구체성**: 단일 구축 사업의 범위와 성과목표 명세
- **요구 추적성**: 요구사항부터 설계•검수까지 연결
- **산정 객관성**: FP•TCO 근거로 규모와 예산 산정
- **발주 실행성**: RFP•평가•계약•검수 기준 통합

#### 한줄 요약

- 요구•목표•비용•발주 조건을 하나의 **기준선**으로 연결

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **FP (Function Point)**: 사용자 관점의 기능량으로 소프트웨어 규모를 측정하는 기법

</details>

```text
[ISMP]
 ├── [As-Is 분석]
 ├── [To-Be 모델]
 ├── [요구사항 명세]
 ├── [규모•예산 산정]
 └── [RFP]
```

| 구성요소 | 책임 |
|---|---|
| As-Is 분석 | 현행 업무•시스템의 **문제점** 식별 |
| To-Be 모델 | 목표 업무•Data•App•기술 **Architecture** 설계 |
| 요구사항 명세 | 기능•비기능 요구와 **추적성** 정의 |
| 규모•예산 산정 | FP•HW/SW•전환 범위와 **TCO** 산정 |
| RFP | 범위•산출물•검수•사업자 선정 기준 명세 |

#### 한줄 요약

- 현행 분석부터 **RFP**까지 발주 근거를 단계별 구체화

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Baseline (기준선)**: 승인 후 변경 통제를 적용하는 범위•요구•비용의 기준 상태

</details>

```text
[전략 과제 인계]
        │
        ▼
[1. 사업 범위•성과목표 확정]
        │
        ▼
[2. As-Is•요구사항 분석]
        │
        ▼
[3. To-Be•전환 모델 설계]
        │
        ▼
[4. 규모•비용•타당성 산정]
        │
        ▼
[5. RFP•이행계획 확정]
        │
        ▼
[발주 자료 반환]
```

### 동작 원리

1. **사업 범위•성과목표 확정**: 전략 과제를 사업 기준선으로 변환
2. **As-Is•요구사항 분석**: 현행 한계와 추적 가능한 요구 도출
3. **To-Be•전환 모델 설계**: 목표 구조와 단계별 전환안 구체화
4. **규모•비용•타당성 산정**: 산정 근거와 투자 판단 자료 확보
5. **RFP•이행계획 확정**: 발주•검수•전환 기준선 확정

#### 한줄 요약

- 전략 과제를 분석•설계•산정해 **발주 자료**로 반환

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ISP (Information Strategy Planning)**: 경영 전략과 연계한 전사 정보화 전략•과제를 수립하는 활동

</details>

| 비교 항목 | ISP | ISMP |
|---|---|---|
| 범위 | **전사 정보화** 전략 | **개별 구축 사업** 실행 |
| 목적 | 과제•우선순위 도출 | 요구•규모•RFP 구체화 |
| 산출물 | 목표 Architecture•로드맵 | 요구명세•예산•발주 자료 |
| 적용 시점 | 투자 과제 선정 전 | 선정 사업의 발주 전 |

#### 한줄 요약

- ISP는 전사 방향, ISMP는 선정 사업의 **실행 명세** 담당

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Scope Creep (범위 잠식)**: 통제되지 않은 요구 추가로 사업 범위가 지속 확장되는 현상

</details>

| 고려사항 | 대책 |
|---|---|
| 요구 누락•모호성 | **요구 추적표•수용 기준**으로 완전성 검증 |
| 범위 잠식 | 기준선 승인과 **변경통제위원회** 운영 |
| 규모•비용 오차 | 복수 산정과 **민감도 분석** 병행 |
| 현업 참여 부족 | 업무 책임자의 **검토•승인 Gate** 지정 |
| 전환 위험 | Migration•Cutover•**Rollback** 계획 수립 |

#### 한줄 요약

- 추적성•변경통제•산정 검증으로 **발주 분쟁** 예방

## Ⅶ. 결론

<details><summary>쉽게 이해하기 (학습용)</summary>

- ISP가 어떤 건물을 지을지 정한다면, ISMP는 선택한 건물의 설계•견적•입찰 조건을 확정한다.

</details>

- 전사 과제 우선순위는 **ISP**, 선정 사업의 발주 명세는 ISMP 적용
