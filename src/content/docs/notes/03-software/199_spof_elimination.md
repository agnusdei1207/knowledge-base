## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **독립 대체 경로**: SPOF 제거는 한 요소의 고장이 전체 서비스 중단으로 전파되지 않도록 독립된 대체 경로를 마련하는 설계다.

</details>

- 정의/개념: **단일 장애점 제거**는 한 구성요소의 고장이 전체 서비스 중단으로 전파되지 않도록 독립된 대체 자원과 경로를 마련하는 **고가용성 설계 기법**
- 배경/필요성: 장비만 이중화하면 공유 전원·망·제어의 **논리적 SPOF** 잔존

### 쉽게 이해하기 (학습용)
- 다리가 하나뿐인 섬은 그 다리가 끊기면 고립되므로 서로 다른 지반과 관리 체계를 쓰는 두 번째 길까지 마련해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **의존성 지도·FMEA**: 의존성 지도와 FMEA는 물리·논리 구성요소의 고장 원인과 전체 서비스 영향을 따라 단일 장애점을 식별한다.

</details>

- **의존성 지도·FMEA** 기반 장애점 식별
- **독립 도메인·다중 경로** 기반 대체 구조
- **DNS·제어 경로**의 장애 도메인 분리
- **헬스 체크·서킷 브레이커** 기반 장애 탐지·전파 차단
- **쿼럼·펜싱**과 장애 주입 기반 전환 검증

### 쉽게 이해하기 (학습용)
- 서버가 두 대여도 같은 전원과 DNS 계정을 쓰면 함께 멈추므로 물리·논리 의존 지도를 따라 공통 고리를 끊는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **제어 경로**: 제어 경로는 장애 판정, 트래픽 전환, 펜싱과 권한 분리를 담당하며 데이터 경로와 독립돼야 한다.

</details>

```mermaid
block
    columns 1
    A["다중 진입"]
    B["서비스 노드"]
    C["데이터 노드"]
    D["제어 경로"]
    E["장애 시험"]
    A --- B
    B --- C
    C --- D
    D --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 다중 진입 | DNS·망·**라우팅 경로 이중화** |
| 서비스 노드 | 독립 도메인·**요청 처리** |
| 데이터 노드 | 복제·쿼럼·**상태 보존** |
| 제어 경로 | 전환·펜싱·**권한 분리** |
| 장애 시험 | 주입·대체 경로·**용량 검증** |

> 요약: 계층별 다중화와 **자동 펜싱**으로 장애 격리

### 쉽게 이해하기 (학습용)
- 입구·서비스·데이터·제어 경로를 서로 다른 장애 도메인에 두고 장애 시험이 한 경로를 끊어도 나머지가 이어지는지 확인한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **2. 대체 경로**: 제어 경로는 장애 노드를 펜싱한 뒤 독립된 진입 경로가 정상 서비스 노드로 향하도록 갱신한다.

</details>

```mermaid
sequenceDiagram
    participant T as 장애 시험
    participant E as 다중 진입
    participant S as 서비스 노드
    participant D as 데이터 노드
    participant C as 제어 경로
    T->>S: 장애 주입
    S->>C: 1. 장애 상태
    C->>E: 2. 대체 경로
    E->>S: 3. 정상 노드 전달
    S->>D: 4. 상태 조회
    D-->>S: 복제 상태
    S-->>T: 검증 응답
```

**동작 원리**

1. **장애 상태**: 처리 불가 노드와 영향 경로 판정
2. **대체 경로**: 펜싱 후 독립 진입 경로 갱신
3. **정상 노드 전달**: 대체 서비스 노드로 트래픽 전달
4. **상태 조회**: 쿼럼이 승인한 복제 상태 사용

> 요약: 장애 주입 후 **독립 대체 경로·상태** 검증

### 쉽게 이해하기 (학습용)
- 장애 시험이 한 서비스 노드를 끊으면 제어 경로가 입구를 바꾸고 정상 노드가 복제 데이터를 읽어 응답하는지 확인한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **수평 다중화**: 수평 다중화는 같은 역할의 무상태 노드를 여러 장애 도메인에 배치해 요청과 장애를 분산한다.

</details>

| SPOF 제거 방식 | 수평 다중화 | Active-Standby | 점진적 기능 저하 |
|:---|:---|:---|:---|
| 적용 기준 | 무상태·**트래픽 확장** | 상태형·**단일 쓰기** | 의존 장애 **전파 차단** |
| 핵심 특징 | 다중 노드 **요청 분산** | 대기 노드 **장애 승격** | 비핵심 기능 **차단** |
| 한계 | 공유 의존성 **잔존** | 승격 실패·**이중 쓰기** | 핵심 기능 **오분류** |

> 요약: **상태·장애 전파 조건**에 따라 다중화·기능 저하 선택

### 쉽게 이해하기 (학습용)
- 무상태 요청은 여러 창구로 나누고 상태형 쓰기는 대기 창구 하나만 승격하며 부가 기능 장애는 핵심 기능에서 분리한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **이중 쓰기**: 이중 쓰기는 상태형 서비스의 이전 노드와 승격 노드가 동시에 같은 데이터를 변경해 정합성을 훼손하는 문제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 노드만 다른 **공유 전원·망** | 물리 경로·**장애 도메인 분리** | 공통 원인 **제거** |
| 대체 경로의 **제어 의존** | 제어·데이터 **영역 분리** | 전환 가능성 **확보** |
| 상태형 서비스의 **이중 쓰기** | 쿼럼·**펜싱 적용** | 데이터 훼손 **방지** |
| 미검증된 **대체 경로 용량** | 정기 장애·**최대 부하 주입 시험** | 실제 전환 **증명** |

### 쉽게 이해하기 (학습용)
- 데이터 노드를 끄는 시험이 제어 경로까지 멈추게 하면 공통 의존성이 남은 것이므로 전원·망·권한을 다시 분리한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **SPOF 제거 완료**: 공통 원인을 분리하고 실제 장애 주입에서 대체 경로 전환을 통과해야 SPOF 제거 완료로 판정할 수 있다.

</details>

- 공통 원인 분리와 장애 주입 전환을 통과해야 **SPOF 제거 완료**, 실패 경로는 재설계

### 쉽게 이해하기 (학습용)
- 서버 수를 세는 대신 한 전원·망·계정 장애를 넣었을 때 대체 경로가 실제 요청을 끝내는지 확인한다.
