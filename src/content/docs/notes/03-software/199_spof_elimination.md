## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **단일 장애점(Single Point of Failure, SPOF) 제거**: 한 구성요소의 고장이 전체 서비스 중단으로 전파되지 않도록 독립된 대체 자원과 경로를 마련하는 고가용성 설계 기법이다.

</details>

- 정의/개념: 독립 대체 자원•경로의 **단일 장애점 제거 기법**이다.
- 배경/필요성: 장비만 이중화하면 공유 전원•망•제어의 **논리적 SPOF** 잔존이 발생한다.

#### 한줄 요약
- 다리가 하나뿐인 섬은 그 다리가 끊기면 고립되므로 서로 다른 지반과 관리 체계를 쓰는 두 번째 길까지 마련해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **의존성 지도(Dependency Map)**: 물리•논리 구성요소와 서비스 사이의 의존 관계를 나타낸 지도이다.
- **고장 형태 및 영향 분석(Failure Mode and Effects Analysis, FMEA)**: 구성요소별 고장 형태•원인•영향•탐지•우선순위를 분석하는 기법이다.
- **도메인 이름 시스템(Domain Name System, DNS)**: 도메인 이름을 서비스 주소로 해석하는 분산 시스템이다.
- **제어 경로(Control Path)**: 장애 판정•트래픽 전환을 담당하는 관리 경로이다.
- **서킷 브레이커(Circuit Breaker)**: 의존 서비스 실패가 임계치를 넘으면 호출을 일시 차단해 장애 전파를 막는 장치이다.

</details>

- **의존성 지도•FMEA** 기반 장애점 식별이 핵심이다.
- **독립 도메인•다중 경로** 기반 대체 구조이다.
- **DNS•제어 경로**의 장애 도메인을 분리한다.
- **헬스 체크•서킷 브레이커** 기반 장애 탐지•전파 차단이 핵심이다.
- **쿼럼•펜싱**과 장애 주입 기반 전환을 검증한다.

#### 한줄 요약
- 서버가 두 대여도 같은 전원과 DNS 계정을 쓰면 함께 멈추므로 물리•논리 의존 지도를 따라 공통 고리를 끊는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **제어 경로**: 제어 경로는 장애 판정, 트래픽 전환, 펜싱과 권한 분리를 담당하며 데이터 경로와 독립돼야 한다.
- **다중 진입(Multiple Entry Paths)**: 도메인 이름 시스템•네트워크•라우팅을 서로 독립된 경로로 구성한 진입 계층이다.
- **서비스 노드(Service Node)**: 독립 장애 도메인에서 실제 업무 요청을 처리하는 구성요소이다.
- **데이터 노드(Data Node)**: 복제•쿼럼으로 상태를 보존하고 정상 노드에 일관된 데이터를 제공하는 구성요소이다.
- **장애 시험(Failure Test)**: 장애 주입 뒤 대체 경로•처리 용량•상태 정합성을 검증하는 구성요소이다.

</details>

```text
[다중 진입] ----- [서비스 노드] ----- [데이터 노드]
                         |                   |
                    [장애 시험]         [제어 경로]
```

선의 의미: 다중 진입, 서비스 노드와 데이터 노드는 업무 데이터 경계를 구성하고, 서비스 노드에는 장애 시험이, 데이터 노드에는 독립적인 전환•펜싱 제어 경로가 결합되는 정적 SPOF 제거 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 다중 진입 | DNS•망•**라우팅 경로 이중화** |
| 서비스 노드 | 독립 도메인•**요청 처리** |
| 데이터 노드 | 복제•쿼럼•**상태 보존** |
| 제어 경로 | 전환•펜싱•**권한 분리** |
| 장애 시험 | 주입•대체 경로•**용량 검증** |

> 요약: 계층별 다중화와 **자동 펜싱**으로 장애 격리가 핵심이다.

#### 한줄 요약
- 입구•서비스•데이터•제어 경로를 서로 다른 장애 도메인에 두고 장애 시험이 한 경로를 끊어도 나머지가 이어지는지 확인한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **1. 장애•영향 경로 판정**: 처리 불가 자원과 전파 범위를 확인하는 단계이다.
- **2. 장애 노드 펜싱•제어 경로 검증**: 기존 쓰기를 차단하고 전환 제어를 확인하는 단계이다.
- **3. 대체 서비스•데이터 준비 검증**: 쿼럼 상태와 처리 용량을 확인하는 단계이다.
- **4. 진입 경로 전환•요청 검증**: 정상 노드로 실제 요청을 완료하는 단계이다.

</details>

```text
서비스•망•전원•계정 장애 주입
      |
      v
1. 장애•영향 경로 판정
      |
      v
2. 장애 노드 펜싱•제어 경로 검증
      |
      +-- 제어 경로 실패 --> 공통 의존성 재설계
      |
      +-- 제어 경로 정상
              |
              v
3. 대체 서비스•데이터 준비 검증
      |
      +-- 상태•용량 미달 --> 전환 차단•보완
      |
      +-- 준비 완료
              |
              v
4. 진입 경로 전환•요청 검증
```

**동작 원리**

1. **장애•영향 경로 판정**: 처리 불가 자원•전파 범위를 확인한다.
2. **장애 노드 펜싱•제어 경로 검증**: 쓰기 차단•전환을 확인한다.
3. **대체 서비스•데이터 준비 검증**: 상태•용량을 점검한다.
4. **진입 경로 전환•요청 검증**: 정상 노드의 요청을 완료한다.

> 요약: 장애 주입 후 **독립 대체 경로•상태**를 검증한다.

#### 한줄 요약
- 장애 시험이 한 서비스 노드를 끊으면 제어 경로가 입구를 바꾸고 정상 노드가 복제 데이터를 읽어 응답하는지 확인한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **수평 다중화**: 수평 다중화는 같은 역할의 무상태 노드를 여러 장애 도메인에 배치해 요청과 장애를 분산한다.
- **액티브-스탠바이(Active-Standby)**: 상태형 서비스에서 하나의 활성 노드만 쓰고 장애 시 펜싱 후 대기 노드를 승격하는 방식이다.
- **점진적 기능 저하(Graceful Degradation)**: 의존 장애 시 비핵심 기능을 차단하고 핵심 기능은 제한적으로 지속하는 방식이다.

</details>

| SPOF 제거 방식 | 수평 다중화 | Active-Standby | 점진적 기능 저하 |
|:---|:---|:---|:---|
| 적용 기준 | 무상태•**트래픽 확장** | 상태형•**단일 쓰기** | 의존 장애 **전파 차단** |
| 핵심 특징 | 다중 노드 **요청 분산** | 대기 노드 **장애 승격** | 비핵심 기능 **차단** |
| 한계 | 공유 의존성 **잔존** | 승격 실패•**이중 쓰기** | 핵심 기능 **오분류** |

> 요약: **상태•장애 전파 조건**에 따라 다중화•기능 저하를 선택한다.

#### 한줄 요약
- 무상태 요청은 여러 창구로 나누고 상태형 쓰기는 대기 창구 하나만 승격하며 부가 기능 장애는 핵심 기능에서 분리한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **이중 쓰기**: 이중 쓰기는 상태형 서비스의 이전 노드와 승격 노드가 동시에 같은 데이터를 변경해 정합성을 훼손하는 문제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 노드만 다른 **공유 전원•망** | 물리 경로•**장애 도메인 분리** | 공통 원인 **제거** |
| 대체 경로의 **제어 의존** | 제어•데이터 **영역 분리** | 전환 가능성 **확보** |
| 상태형 서비스의 **이중 쓰기** | 쿼럼•**펜싱 적용** | 데이터 훼손 **방지** |
| 미검증된 **대체 경로 용량** | 정기 장애•**최대 부하 주입 시험** | 실제 전환 **증명** |

#### 한줄 요약
- 데이터 노드를 끄는 시험이 제어 경로까지 멈추게 하면 공통 의존성이 남은 것이므로 전원•망•권한을 다시 분리한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **SPOF 제거 완료**: 공통 원인을 분리하고 실제 장애 주입에서 대체 경로 전환을 통과해야 SPOF 제거 완료로 판정할 수 있다.

</details>

- 공통 원인 분리와 장애 주입 전환을 통과해야 **SPOF 제거 완료**, 실패 경로는 재설계가 핵심이다.

#### 한줄 요약
- 서버 수를 세는 대신 한 전원•망•계정 장애를 넣었을 때 대체 경로가 실제 요청을 끝내는지 확인한다.
