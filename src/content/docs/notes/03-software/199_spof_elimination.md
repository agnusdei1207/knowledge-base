## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **단일 장애점(SPOF: Single Point of Failure)**: 시스템을 구성하는 특정 하드웨어, 소프트웨어, 네트워크 장비 중 단 하나라도 고장 났을 때 전체 시스템이 마비되는 치명적 취약 지점.
- **숨겨진 논리적 단일 장애점(Hidden Logical SPOF Risk)**: 서버를 이중화했음에도 불구하고 공통 전원 공급 장치(UPS), 단일 DNS 계정, 공유 파일 스토리지, 단일 인증 DB 등 보이지 않는 단일 종속성으로 인해 시스템 전체가 동시 마비되는 위험.

</details>

- 정의/개념: 단일 구성요소의 결함이 전체 시스템 마비로 이어지지 않도록 **물리·논리적 의존성을 식별하고 다중화 및 격리하는 내결함성 설계** 기법
- 배경/필요성: 서버 이중화에도 불구하고 공통 전원, 단일 DNS, 동일 공유 스토리지 등 **숨겨진 단일 장애점(SPOF)으로 인한 전사 서비스 마비 위험** 직면

#### 한줄 요약

- 의존성 지도(Dependency Map)와 FMEA 분석을 통해 물리·논리적 단일 장애점을 전면 제거하고 셀 아키텍처 및 서킷 브레이커로 장애 격리를 달성

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **고장 형태 및 영향 분석(FMEA: Failure Mode and Effects Analysis)**: 각 시스템 구성요소의 고장 모드(Failure Mode)와 잠재적 파급 영향을 체계적으로 평가하여 SPOF를 발굴하는 기법.
- **서킷 브레이커(Circuit Breaker)**: 장애가 발생한 외부 서비스로의 호출을 즉시 차단하여 스레드 고갈 및 연쇄 장애(Cascading Failure) 전파를 막는 방어 패턴.

</details>

- 시스템 전체의 하드웨어, 소프트웨어, 네트워크 의존성을 전수 조사하는 **의존성 맵 기반 가시화**
- 전원, 스위치, 가용영역(AZ)을 완전히 분리하는 **물리적·논리적 다중화(Redundancy)**
- 제어 경로(Control Plane)와 데이터 경로(Data Plane)를 분리하는 **대역 외(Out-of-Band) 관리 체계**

#### 한줄 요약

- 다중 AZ 분산, 데이터 복제, 서킷 브레이커, 카오스 엔지니어링을 통해 단일 실패 지점을 완벽히 소멸

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SPOF 제거 4대 계층 아키텍처**: 진입 계층(DNS/GSLB), 서비스 계층(Multi-AZ), 데이터 계층(분산 복제/쿼럼), 제어 계층(Out-of-Band Fencing).

</details>

```text
[ 단일 장애점(SPOF) 제거 엔드-투-엔드 아키텍처 구조도 ]

 1. [ 진입 계층 (Entry Layer) ] ── (다중 DNS 프로바이더 + 멀티 CDN)
              │
              ▼
 2. [ 서비스 계층 (Service Layer) ] ─────────────────────────────┐
    • Multi-AZ 무상태(Stateless) 파드 분산 + 셀 아키텍처(Cell)   │
    • 서킷 브레이커(Resilience4j)로 외부 장애 연쇄 전파 차단      │
    └─────────┬───────────────────────────────────────────────────┘
              │
              ▼
 3. [ 데이터 계층 (Data Layer) ] ────────────────────────────────┐
    • etcd 3노드 쿼럼 합의 + Multi-AZ 동기 복제 + 불변 백업(WORM) │
    └─────────┬───────────────────────────────────────────────────┘
              │
              ▼
 4. [ 제어 계층 (Control Plane Layer) ]
    • 별도 VLAN/VPN 대역 외(Out-of-Band) 관리망 및 독립 펜싱 에이전트
```

선의 의미: 진입, 서비스, 데이터, 제어의 전 계층에서 공통 의존성을 제거하고 독립 장애 도메인으로 격리한 구조.

| 구성요소 | 책임 |
|:---|:---|
| 진입 계층 (Entry) | 다중 DNS 및 멀티 CDN을 구성하여 **도메인 네임서버 장애 시에도 접속 경로 유지** |
| 서비스 계층 (Service) | Multi-AZ 수평 확장 및 서킷 브레이커로 **특정 서버/AZ 고장 시에도 무중단 처리** |
| 데이터 계층 (Data) | Raft 쿼럼 및 교차 리전 동기 복제로 **단일 DB 장애 시 데이터 유실 없이 승격** |
| 제어 계층 (Control) | 서비스 망과 분리된 독립 대역 외(Out-of-Band) 관리망으로 **장애 노드 강제 격리** |

#### 한줄 요약

- 진입, 서비스, 데이터, 제어 계층이 완벽히 독립된 장애 도메인으로 분리되어 SPOF를 제거

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SPOF 제거 5단계 수명주기**: 의존성 지도 작성 $\to$ FMEA 고장 분석 $\to$ SPOF 목록화 $\to$ 다중화/격리 설계 $\to$ 장애 주입(Fault Injection) 검증.

</details>

```text
[ SPOF 식별, 다중화 설계 및 카오스 검증 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 전사 시스템 의존성 지도(Map) 작성   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. FMEA 기반 구성요소별 고장 영향도 분석│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 단일 고장 시 전사 마비되는 SPOF 식별│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. Multi-AZ 다중화 및 서킷 브레이커 설계│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. Fault Injection 장애 주입 실증 검증 │
 └────────────────────────────────────────┘
```

### 동작 원리

1. 지도 작성: 웹 서버부터 DB, DNS, 전원 PDU, 서드파티 결제 PG사까지의 전사 호출 그래프를 작성.
2. FMEA 분석: 단일 부품의 고장 형태와 심각도(RPN)를 산출하여 단일 장애 파급 경로를 전수 분석.
3. SPOF 도출: 공유 인증 서버(Redis) 및 단일 사내 DNS가 전체 서비스의 핵심 SPOF임을 확인.
4. 다중화 설계: Redis 클러스터를 Multi-AZ 센티널로 이중화하고, 외부 퍼블릭 DNS를 보조 네임서버로 추가.
5. 장애 검증: Chaos Mesh를 통해 프라이머리 Redis 파드를 강제 킬(Kill)하여 서비스 중단 없이 즉시 페일오버됨을 검증.

#### 한줄 요약

- 의존성 작성 $\to$ FMEA 분석 $\to$ SPOF 도출 $\to$ 다중화 설계 $\to$ 장애 주입 검증의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SPOF 제거 3대 접근 전략**: 무상태 수평 다중화, 상태형 쿼럼 이중화, 기능 점진적 저하(Graceful Degradation).

</details>

| 구분 | 무상태 수평 다중화 (Horizontal Redundancy) | 상태형 쿼럼 이중화 (Stateful Quorum) | 점진적 기능 저하 (Graceful Degradation) |
|:---|:---|:---|:---|
| **적용 기준** | 웹 서버, API 게이트웨이, 무상태 마이크로서비스 | 핵심 RDBMS, NoSQL, 분산 코디네이터(etcd) | AI 추천 엔진, 댓글, 마케팅 배너 등 비핵심 외부 의존 |
| **핵심 특징** | **다중 AZ에 N개 노드 분산 배포, 로드밸런서 자동 제외** | **과반수 합의(Quorum) 기반 자동 승격 및 동기식 복제** | **서킷 브레이커로 외부 장애를 차단하고 캐시된 더미 반환** |
| **한계** | 백엔드 상태 저장소(DB)가 여전히 SPOF로 남을 위험 | 스플릿 브레인 방지를 위한 최소 3노드 이상 비용 소요 | 핵심 비즈니스(결제 본체)에는 적용 불가(부가 기능 한정) |

#### 한줄 요약

- 무상태는 수평 다중화, 데이터베이스는 쿼럼 이중화, 부가 기능은 서킷 브레이커 점진적 저하를 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **피해 반경(Blast Radius) 격리**: 셀 아키텍처(Cell Architecture)를 적용하여 특정 셀의 장애가 전체 고객에게 전파되지 않고 해당 셀의 1% 사용자에게만 국한되도록 억제하는 통제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 이중화 후 동일한 공유 스토리지(NFS) 장애로 전사 다운 | **공유 스토리지 종속을 제거하고 분산 객체 스토리지(S3/Ceph)로 전환** | 인프라 단일 장애점 100% 제거 |
| 서비스 망과 관리망이 동일하여 네트워크 마비 시 페일오버 명령 불가 | **별도 VLAN 및 콘솔 기반 '대역 외(Out-of-Band) 관리망' 구축** | 비상 원격 제어 통제권 확보 |
| 설계 상으로만 SPOF를 제거하고 실제 운영 장애 시 페일오버 실패 | **정기적 카오스 엔지니어링(Chaos Monkey) 장애 주입 테스트 의무화** | 실전 내결함성 신뢰도 확보 |

#### 한줄 요약

- 공유 스토리지 제거, 대역 외 관리망 분리, 정기 카오스 테스트를 통해 완벽한 SPOF 제로화를 달성

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **셀 기반 무결함 아키텍처(Cell-Based Architecture)**: 전체 시스템을 독립적인 세포(Cell) 단위로 쪼개어 단 하나의 세포가 전소되더라도 타 세포에 일체 영향을 주지 않는 궁극의 고가용성 설계.

</details>

- **단일 장애점(SPOF) 제거**는 서비스 연속성을 보장하기 위한 가장 근본적인 엔지니어링 과제이며, 의존성 지도와 FMEA 분석을 바탕으로 전 계층 다중화와 카오스 엔지니어링 검증을 지속 실천해야 함

#### 한줄 요약

- 전 계층 독립 다중화와 서킷 브레이커 및 장애 주입 검증을 통해 단일 장애점을 완벽히 제거
