## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서킷 브레이커 패턴(Circuit Breaker Pattern)**: 원격 서비스 호출의 실패율을 모니터링하여 임계치 초과 시 추가 호출을 즉시 차단하고 대체 응답을 반환함으로써 시스템 연쇄 장애를 방지하는 안정성 설계 패턴.
- **연쇄 장애(Cascading Failure)**: 단일 서비스의 지연이나 장애가 해당 서비스를 호출하는 상위 서비스의 스레드 풀 고갈 및 타임아웃으로 전파되어 시스템 전체가 마비되는 현상.
- **대체 응답(Fallback)**: 대상 서비스 장애 또는 서킷 개방(Open) 상태에서 원격 호출 대신 캐시된 데이터나 사전 정의된 기본값을 즉시 반환하는 장애 완화 기법.

</details>

- 정의/개념: 원격 서비스 호출 실패율이 임계치를 초과할 때 연결을 즉시 차단하여 **연쇄 장애(Cascading Failure)** 를 방지하고 복구 상태를 자동 감지하는 안정성 패턴
- 배경/필요성: 분산 마이크로서비스 환경에서 피호출 서비스의 응답 지연 시 호출자 측 스레드 풀 고갈 및 자원 잠식 현상 해소 요구

#### 한줄 요약
- 원격 호출 실패율에 따라 연결을 자동 차단 및 복구하여 시스템 전반으로의 장애 전파를 방지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **정상 상태(Closed)**: 원격 서비스 호출이 정상적으로 전달되고 실행 결과를 수신하는 서킷 브레이커의 기본 운영 상태.
- **차단 상태(Open)**: 실패율이 설정된 임계치를 초과하여 원격 서비스로의 호출을 즉시 중단하고 대체 응답을 반환하는 상태.
- **반개방 상태(Half-Open)**: 차단 대기 시간 경과 후 소수의 시험 호출을 전송하여 대상 서비스의 정상 복구 여부를 판정하는 상태.

</details>

- **Closed $\rightarrow$ Open $\rightarrow$ Half-Open $\rightarrow$ Closed** 로 이어지는 3단계 상태 전이 머신 기반 제어
- **슬라이딩 윈도우(Sliding Window)** 기반의 호출 통계(횟수 기반 또는 시간 기반) 측정 및 실패율 산출
- 장애 격리 후 **대체 응답(Fallback)** 반환을 통한 서비스 부분 가용성(Graceful Degradation) 보장

#### 한줄 요약
- 3단계 상태 전이와 슬라이딩 윈도우 통계를 기반으로 장애를 격리하고 대체 응답을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **슬라이딩 윈도우(Sliding Window)**: 최근 N회의 호출 결과(카운트 기반) 또는 최근 T초 동안의 호출 결과(시간 기반)를 링 버퍼에 보관하여 실패율을 계산하는 통계 기법.
- **격벽 패턴(Bulkhead Pattern)**: 서비스별로 스레드 풀이나 세마포어 자원을 물리적으로 격리하여 특정 원격 서비스 장애가 타 서비스 자원을 고갈시키지 않도록 분리하는 패턴.

</details>

```text
[ 클라이언트 요청 ]
        │
        ▼
[ 서킷 브레이커 인터셉터 ] ───(호출 통계)───▶ [ 슬라이딩 윈도우 (실패율 계측) ]
        │                                             │ (임계치 초과 판정)
        ├─ Closed 상태: [ 원격 마이크로서비스 호출 ]    ▼
        │                                    [ 상태 머신 (Closed/Open/Half-Open) ]
        └─ Open 상태:   [ 대체 응답기 (Fallback) ] ◀───┘
```

선의 의미: 인터셉터는 호출을 중계하며, 통계 계측 결과에 따라 상태 머신이 호출 경로를 분기

| 구성요소 | 책임 |
|:---|:---|
| **호출 인터셉터** | 원격 호출 요청을 가로채 현재 서킷 상태에 따라 호출 허용 또는 차단 |
| **슬라이딩 윈도우** | 링 버퍼 기반으로 최근 호출 성공/실패 횟수 및 응답 지연 시간을 집계 |
| **상태 관리 머신** | 실패율 임계치 및 쿨다운 타이머에 따라 Closed, Open, Half-Open 전이 수행 |
| **대체 응답 처리기** | Open 상태 또는 타임아웃 발생 시 사전 정의된 Fallback 데이터 반환 |

#### 한줄 요약
- 호출 인터셉터와 슬라이딩 윈도우 통계를 연동하여 상태를 전이시키고 Fallback을 실행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **시험 호출(Probe Request)**: Half-Open 상태에서 대상 서비스의 복구 여부를 판정하기 위해 제한된 수량으로 허용되는 테스트 요청.

</details>

```text
1. Closed 상태 호출 수행 및 통계 수집
            │
            ▼ (실패율 임계치 초과)
2. Open 상태 전이: 원격 호출 즉시 차단 및 Fallback 반환
            │
            ▼ (대기 시간/쿨다운 만료)
3. Half-Open 상태 전이: 제한된 수량의 시험 호출(Probe) 전송
            │
            ├─ 시험 호출 성공 (복구 확인) ──▶ 4a. Closed 상태 복귀
            └─ 시험 호출 실패 (장애 지속) ──▶ 4b. Open 상태 재진입
```

**동작 원리**

1. **정상 호출 및 집계**: Closed 상태에서 원격 요청을 처리하고 실패율 및 지연율을 슬라이딩 윈도우에 기록
2. **차단 판정**: 실패율이 기준치(예: 50%)를 초과하면 Open 상태로 즉시 전이하여 후속 요청을 차단하고 Fallback 반환
3. **쿨다운 대기**: 설정된 대기 시간(예: 10초) 동안 원격 서비스의 부하를 차단하여 복구 시간 제공
4. **시험 호출 전송**: 대기 시간 만료 시 Half-Open 상태로 진입하여 제한된 수의 시험 요청 허용
5. **상태 복귀/재차단**: 시험 요청이 성공 기준을 만족하면 Closed로 정상화하고, 실패 시 다시 Open으로 전이

#### 한줄 요약
- 임계치 초과 시 차단(Open) 후 쿨다운을 거쳐 시험 호출(Half-Open) 결과에 따라 정상화(Closed)한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Resilience4j**: 함수형 인터페이스 기반으로 서킷 브레이커, Rate Limiter, Retry, Bulkhead 등을 모듈형으로 제공하는 경량 라이브러리.
- **Netflix Hystrix**: RxJava 및 전용 스레드 풀 격리 기반으로 설계되었으나 현재 유지보수가 중단(Deprecated)된 레거시 라이브러리.

</details>

| 비교 항목 | Resilience4j | Netflix Hystrix (Deprecated) | Envoy / Istio (Service Mesh) |
|:---|:---|:---|:---|
| **적용 기준** | Spring Boot/Cloud 기반 Java 마이크로서비스 | 레거시 스프링 클라우드 유지보수 시스템 | 다국어(Polyglot) 분산 마이크로서비스 인프라 |
| **구현 계층** | 애플리케이션 라이브러리 계층 | 애플리케이션 라이브러리 계층 | 인프라 사이드카(Sidecar) 프록시 계층 |
| **핵심 특징** | 경량 함수형 데코레이터 및 모듈별 독립 선택 | 스레드 풀 격리 강제 및 무거운 런타임 오버헤드 | 코드 수정 없는 L7 트래픽 가로채기 및 서킷 차단 |
| **한계** | JVM 언어 종속적 적용 | 유지보수 중단 및 자원 소모량 과다 | 프록시 추가로 인한 네트워크 홉 지연(Latency) |

#### 한줄 요약
- JVM 환경에서는 모듈형 Resilience4j를, 다국어 분산 환경에서는 서비스 메시 사이드카 방식을 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최소 호출 수(Minimum Number of Calls)**: 통계 표본 부족으로 인한 비정상적인 조기 서킷 개방을 방지하기 위해 필요한 최소 집계 호출 건수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 트래픽 유입 초기에 단발성 오류로 인한 오차단 발생 | 최소 호출 건수(`minimumNumberOfCalls`)를 적정 수준(20~50회)으로 설정 | 통계 신뢰도 확보 및 조기 오차단 방지 |
| 피호출 서비스 지연 시 호출자 스레드 풀 동반 고갈 | 서킷 브레이커와 **격벽 패턴(Bulkhead)** 을 결합하여 전용 자원 격리 | 스레드 고갈 방지 및 독립적 결함 격리 |
| 서킷 개방 시 클라이언트 오류 응답 급증 | 캐시 데이터 또는 안전한 기본값을 반환하는 **대체 응답(Fallback)** 구현 | 서비스 연속성 유지 및 사용자 경험 훼손 최소화 |

#### 한줄 요약
- 최소 호출 표본 설정, 격벽 자원 격리, Fallback 캐시 설계를 통해 안정성을 확보한다.

## Ⅶ. 결론

- 마이크로서비스 간 원격 통신 구간에는 **서킷 브레이커(Resilience4j/Envoy)** 를 기본 적용하고, 스레드 풀 고갈 방지를 위한 **Bulkhead** 및 타임아웃 설정을 복합 연계하여 분산 시스템의 회복탄력성(Resilience)을 보장

#### 한줄 요약
- 원격 서비스 호출의 실패율과 복구 상태를 자동 감지하여 분산 시스템의 결함 전파를 원천 차단한다.
