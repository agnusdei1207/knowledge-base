## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **서킷 브레이커(Circuit Breaker)**: 원격 호출의 연속 실패를 감지해 호출을 차단하고 시험 호출로 복구를 확인하는 장애 격리 패턴이다.
- **장애 격리**: 실패한 의존 서비스가 호출자의 스레드•연결 풀까지 고갈시키지 않도록 영향 범위를 제한하는 방식이다.

</details>

- 정의/개념: **서킷 브레이커**는 원격 호출 실패가 임계치를 넘으면 후속 호출을 차단하고 제한된 시험 호출로 복구를 판정한다.
- 배경/필요성: 장애 서비스 반복 호출은 스레드•연결 풀 고갈을 일으키므로 **장애 격리**가 필요하다.

#### 한줄 요약

- 실패 임계치 차단과 시험 호출 기반 **서킷 브레이커**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **열림 상태(Open State)**: 실패 임계치 초과 뒤 원격 호출을 즉시 차단하는 상태이다.
- **닫힘 상태(Closed State)**: 원격 호출을 정상 전달하면서 결과를 실패 측정 창에 누적하는 상태이다.
- **반열림 상태(Half-Open State)**: 제한된 시험 호출만 허용해 의존 서비스의 복구 여부를 판정하는 상태이다.
- **실패 측정 창(Failure Window)**: 최근 호출의 오류•지연 비율을 계산하는 표본 구간이다.

</details>

- **Open**에서 호출을 차단해 의존 서비스의 복구 여력을 보호한다.
- **Half-Open**에서 제한된 시험 호출로 복구를 판정한다.
- **실패 측정 창**으로 차단 민감도를 조정하고 **Closed**에서 결과를 누적한다.

#### 한줄 요약

- **Closed**, **Open**, **Half-Open** 상태 전이가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **호출 인터셉터(Call Interceptor)**: 원격 요청을 가로채 차단 상태에 따라 전달하거나 즉시 실패시키는 구성요소이다.
- **상태 기계(State Machine)**: 호출 결과•대기 시간•시험 결과에 따라 닫힘•열림•반열림 상태를 전환하는 모델이다.
- **대체 응답(Fallback)**: 원격 결과 대신 업무가 허용한 캐시•기본값•명시 오류를 반환하는 처리이다.

</details>

```text
[호출 인터셉터] -------- [실패 측정 창] -------- [상태 기계]
                                                     /     \
                                                    /       \
                                         [복구 제어기]     [대체 응답 처리기]
```

선의 의미: 호출 인터셉터와 실패 측정 창의 선은 호출 결과 표본 제공 관계, 실패 측정 창과 상태 기계의 선은 실패율•지연율 판단 자료 제공 관계, 상태 기계에서 갈라지는 선은 차단 상태에 따라 복구 제어기 또는 대체 응답 처리기의 정책을 사용하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 호출 인터셉터 | **호출 인터셉터**가 차단 상태에 따라 호출 전달•즉시 실패 |
| 실패 측정 창 | 최소 표본의 실패율•지연율 집계 |
| 상태 기계 | **상태 기계**가 Closed•Open•Half-Open 상태 전환 |
| 복구 제어기 | 열림 대기 시간•시험 호출량 제어 |
| 대체 응답 처리기 | **대체 응답**으로 캐시•기본값•명시 오류 반환 |

#### 한줄 요약

- **호출 인터셉터**, **상태 기계**, **대체 응답**이 차단과 복구를 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **호출 허용•타임아웃**: Closed 상태에서 원격 요청을 제한 시간과 함께 전달하는 단계이다.
- **결과 집계•임계 판정**: 성공•오류•지연 표본으로 Open 전환 조건을 확인하는 단계이다.
- **Open 즉시 차단**: 후속 원격 호출을 보내지 않고 대체 응답이나 명시 오류를 반환하는 단계이다.
- **Open 대기 만료**: 설정한 복구 대기 시간이 지나면 Half-Open으로 전환하는 단계이다.
- **Half-Open 시험 판정**: 제한된 시험 호출의 성공은 Closed, 실패는 Open으로 전환하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ Closed                      │◀────────────────┐
└──────────────┬───────────────┘                 │
               ▼                                 │
┌──────────────────────────────┐                 │
│ 1. 호출 허용•타임아웃      │                 │
└──────────────┬───────────────┘                 │
               ▼                                 │
┌──────────────────────────────┐                 │
│ 2. 결과 집계•임계 판정     │                 │
└───────┬──────────────────────┘                 │
        ├─ 임계 미만 ────────────────────────────┘
        │ 임계 초과
        ▼
┌──────────────────────────────┐
│ Open                        │
│ 3. Open 즉시 차단          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. Open 대기 만료          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ Half-Open                   │
│ 5. Half-Open 시험 판정     │
└───────┬──────────────────────┘
        ├─ 성공 ────────────────────────────────▶ Closed
        └─ 실패 ────────────────────────────────▶ Open
```

### 동작 원리

1. **호출 허용•타임아웃**으로 Closed 요청을 제한 시간 안에 전달한다.
2. **결과 집계•임계 판정**으로 Open 전환 여부를 결정한다.
3. **Open 즉시 차단**으로 원격 호출 없이 대체 결과를 반환한다.
4. **Open 대기 만료** 뒤 Half-Open으로 전환한다.
5. **Half-Open 시험 판정**에서 성공하면 Closed, 실패하면 Open으로 전환한다.

#### 한줄 요약

- **결과 집계•임계 판정**과 **Half-Open 시험 판정**의 상태 순환이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **재시도(Retry)**: 회복 가능한 일시 오류가 난 호출을 제한된 횟수와 간격으로 다시 수행하는 방식이다.
- **백오프(Backoff)**: 재시도 간격을 점차 늘리는 방식이다.
- **지터(Jitter)**: 재시도 시점에 무작위 편차를 더하는 방식이다.
- **지연 예산(Latency Budget)**: 전체 요청이 허용하는 최대 응답 시간으로 타임아웃과 재시도의 합이 넘지 않아야 하는 한도이다.

</details>

| 장애 대응 방식 | 서킷 브레이커 | 재시도 |
|:---|:---|:---|
| 적용 기준 | 반복 장애가 호출 자원을 소모할 때 | **지연 예산** 안에 회복 가능한 일시 오류 |
| 핵심 특징 | 서킷 브레이커의 임계치 이후 호출 차단•제한 검증 | **재시도**에 **백오프**•**지터** 적용 |
| 한계 | 과민 차단•복구 지연•낡은 대체값 | 재시도 폭풍•지연 예산 초과 |

> 요약: 회복 가능한 일시 오류는 **재시도**, 지속 장애는 호출 차단이 핵심이다.

#### 한줄 요약

- 일시 오류는 재시도, 지속 장애는 **서킷 브레이커**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최소 표본(Minimum Sample Size)**: 실패율을 계산하기 전에 측정 창에 모여야 하는 최소 호출 수이다.
- **재시도 폭풍(Retry Storm)**: 다수 호출자가 장애 서비스에 반복 재시도해 복구 자원과 네트워크를 다시 고갈시키는 현상이다.
- **낡은 캐시(Stale Cache)**: 원본 서비스의 최신 변경이 아직 반영되지 않은 캐시 값이다.
- **멱등키(Idempotency Key)**: 같은 업무 요청의 재전송을 식별해 부작용을 한 번만 반영하게 하는 고유 값이다.
- **검증 동시 수(Probe Concurrency)**: 반열림 상태의 동시 시험 호출 한도이다.
- **점진 허용(Gradual Allowance)**: 성공에 따라 시험 호출 허용량을 늘리는 제어이다.
- **최대 노후도(Maximum Staleness)**: 업무가 대체 응답의 오래된 값을 허용할 수 있는 최대 시간 차이다.
- **오차단(False Trip)**: 실제 지속 장애가 아닌데도 측정 오차나 공유 범위 때문에 정상 호출 경로를 차단한 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적은 표본의 우연한 실패로 과민 차단 | **최소 표본**•실패 측정 창별 임계치 설정 | 불필요한 Open 전환 감소 |
| Half-Open 호출 집중으로 의존 서비스 복구 방해 | **검증 동시 수** 제한•**점진 허용** | 안전한 복구 탐색 |
| 재시도와 차단기 설정 분리로 지연 예산 초과 | 타임아웃•백오프•지터 통합 설정 | **재시도 폭풍**•장기 대기 방지 |
| 대체 응답을 최신값으로 오인해 잘못된 업무 처리 | 허용 업무•**최대 노후도** 명시 | **낡은 캐시** 오용 방지 |
| 모든 의존 호출의 상태 공유로 장애 범위 확대 | 서비스•호출 유형•지역별 차단기 분리 | 정상 경로 **오차단** 방지 |
| 결제 재시도가 같은 요청을 중복 반영 | **멱등키**로 동일 업무 요청 식별 | 중복 결제 방지 |

#### 한줄 요약

- **최소 표본**, **검증 동시 수**, **최대 노후도**를 통제한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **일시 오류**: 짧은 시간 뒤 재호출하면 지연 예산 안에서 회복될 가능성이 큰 실패이다.
- **지속 장애**: 반복 호출이 자원 고갈을 키우므로 차단 뒤 시험 호출로 복구를 확인해야 하는 실패이다.
- **장애 대응 선택 기준**: 오류 지속성과 지연 예산을 비교해 재시도와 서킷 브레이커 중 적합한 방식을 고르는 기준이다.

</details>

- **일시 오류**는 **재시도**, **지속 장애**는 **서킷 브레이커**를 선택하는 것이 **장애 대응 선택 기준**이다.

#### 한줄 요약

- 오류 지속성과 지연 예산을 함께 평가하는 것이 핵심이다.
