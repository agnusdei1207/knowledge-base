## 미리 알고가기

- **데이터 독립성(Data Independence)**: 하위 스키마 변경을 매핑에서 흡수해 상위 스키마와 응용 프로그램의 변경을 줄이는 성질임
- **외부 스키마(External Schema)**: 사용자나 응용 프로그램별로 필요한 데이터 표현을 정의한 뷰임
- **개념 스키마(Conceptual Schema)**: 데이터베이스 전체의 개체·관계·제약을 정의한 논리 구조임
- **내부 스키마(Internal Schema)**: 파일·페이지·인덱스 등 데이터의 물리 저장 구조를 정의한 명세임
- **물리적 독립성(Physical Data Independence)**: 내부 스키마 변경을 개념·외부 스키마 변경 없이 수용하는 성질임
- **논리적 독립성(Logical Data Independence)**: 개념 스키마 변경을 외부 스키마·응용 프로그램 변경 없이 수용하는 성질임
- **외부-개념 매핑(External-Conceptual Mapping)**: 사용자별 외부 표현을 전체 개념 구조에 연결하는 변환 규칙임
- **개념-내부 매핑(Conceptual-Internal Mapping)**: 개념 구조를 물리 저장 경로에 연결하는 변환 규칙임
- **호환 뷰(Compatibility View)**: 변경 전 구조와 같은 열과 의미를 제공해 기존 질의를 계속 지원하는 뷰임
- **성능 회귀(Performance Regression)**: 변경 뒤 기존 처리보다 응답 시간이나 자원 사용량이 나빠지는 현상임

## Ⅰ. 개요

- 정의/개념: 하위 스키마 변경을 **매핑에서 흡수**하는 성질
- 기존 한계: 저장·논리 구조 변경이 **응용 수정으로 전파**

### 쉽게 이해하기 (학습용)
- 창고 선반을 바꿔도 화면을 고치지 않게 층 사이 번역표를 두는 원리임

## Ⅱ. 특징

- **물리적 독립성**은 저장 구조 변경을 매핑에서 흡수
- **논리적 독립성**은 개념 구조 변경을 뷰에서 흡수
- 의미 변경은 **호환 뷰·매핑 복잡도** 증가

### 쉽게 이해하기 (학습용)
- 저장 방식 변경은 물리적으로 업무 구조 변경은 논리적으로 사용자를 보호함

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 외부 스키마 | 사용자 뷰와 데이터 표현을 정의함 |
| 외부-개념 매핑 | 외부 표현을 개념 구조에 연결하고 논리 변경을 변환함 |
| 개념 스키마 | 개체와 관계 및 제약을 논리적으로 정의함 |
| 개념-내부 매핑 | 개념 구조를 파일과 인덱스 등 물리 경로에 연결함 |
| 내부 스키마 | 레코드 배치와 접근 경로를 정의함 |

```text
  외부스키마
      ↓
  개념매핑
      ↓
  개념스키마
      ↓
  내부매핑
      ↓
  내부스키마
```

> 요약: 매핑으로 하위 변경의 상위 전파 제한

### 쉽게 이해하기 (학습용)
- 화면과 상품 체계 및 창고 배치 사이에 번역표를 두는 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
  계층분류
      ↓
  변환설계
      ↓
  계약유지
      ↓
  회귀검증
```

| 절차 | 설명 |
|:---|:---|
| **변경 계층 분류** | 변경이 논리 개념 구조인지 물리 내부 구조인지 구분함 |
| **매핑 변환 설계** | 해당 매핑에서 흡수할 계층 간 변환을 설계함 |
| **상위 계약 유지** | 호환 뷰와 버전 및 옵티마이저로 상위 응용 계약을 유지함 |
| **회귀 검증** | 쿼리 변경 건수와 오류 및 지연으로 독립성을 검증함 |

> 요약: 변경 계층을 매핑에서 흡수해 계약 보호

### 쉽게 이해하기 (학습용)
- 어느 층인지 정하고 번역표만 바꾼 뒤 위층 업무가 그대로인지 검증함

## Ⅴ. 종류 및 비교

| 데이터 독립성 유형 | 물리적 독립성 | 논리적 독립성 |
|:---|:---|:---|
| 적용 기준 | 인덱스·파일의 **저장 구조 변경** | 컬럼·테이블의 **논리 구조 변경** |
| 핵심 특징 | 개념-내부 **매핑으로 흡수** | 외부-개념 **매핑으로 흡수** |
| 한계 | 실행 계획·**성능 회귀** | 뷰 복잡도·**의미 호환 한계** |

> 요약: 물리는 저장, 논리는 개념 변경을 흡수

### 쉽게 이해하기 (학습용)
- 물리 독립성은 창고 배치를 논리 독립성은 상품 분류 변경을 감춤

## Ⅵ. 실무 사례

1. 인덱스 변경을 **물리 매핑으로 흡수**
2. 테이블 분리를 **호환 뷰로 흡수**

### 쉽게 이해하기 (학습용)
- 파티션과 인덱스 같은 내부 저장 구조를 바꾼 뒤 응용 질의와 결과가 그대로면 물리적 독립성이 유지된 것임
- 테이블을 분리해도 호환 뷰가 기존 열과 의미를 제공하면 응용 변경 없이 논리적 독립성을 확보할 수 있음

## Ⅶ. 결론

- 저장 변경은 **물리**, 구조 변경은 **논리 독립성**

### 쉽게 이해하기 (학습용)
- 데이터 독립성은 모든 변경을 숨기는 성질이 아니라 어느 계층의 변화를 어떤 매핑과 호환 계약으로 흡수할지 정하는 설계임
