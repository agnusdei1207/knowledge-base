## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 독립성(Data Independence)**: 하위 스키마나 저장 구조의 변경을 계층 간 매핑에서 흡수해 상위 스키마와 응용의 변경을 줄이는 설계 원칙이다.

</details>

- 정의/개념: 하위 변경을 매핑에서 흡수하는 **데이터 독립성** 설계 원칙이다.
- 배경/필요성: 스키마•저장 변경이 응용까지 전파되면 유지보수 비용이 급증한다.

#### 한줄 요약
- 창고 선반을 바꿔도 화면을 고치지 않게 층 사이 번역표를 두는 원리이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **물리 독립성**: 파일•페이지•인덱스 같은 저장 구조 변경을 개념-내부 매핑에서 흡수하는 성질이다.
- **논리 독립성**: 개념 스키마의 개체•관계•제약 변경을 외부-개념 매핑에서 흡수하는 성질이다.
- **영향 전파 범위**: 한 계층의 변경으로 수정해야 하는 상위 스키마와 응용의 범위이다.

</details>

- **물리 독립성**: 저장 구조 변경을 내부 매핑에서 흡수이다.
- **논리 독립성**: 개념 구조 변경을 외부 매핑에서 흡수이다.
- 변경 자체가 아니라 **영향 전파 범위**를 통제한다.

#### 한줄 요약
- 저장 방식 변경은 물리적 독립성으로, 업무 구조 변경은 논리적 독립성으로 사용자를 보호한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **외부-개념 매핑**: 사용자별 데이터 표현을 전체 개념 구조에 연결하는 변환 규칙이다.
- **외부 스키마**: 응용이나 사용자별 데이터 표현과 뷰를 정의한 계층이다.
- **개념 스키마**: 조직 전체 데이터의 개체•관계•제약을 정의한 논리 계층이다.
- **개념-내부 매핑**: 개념 스키마의 구조를 파일•페이지•인덱스 같은 물리 접근 경로에 연결하는 규칙이다.
- **내부 스키마**: 데이터의 실제 파일 조직과 페이지 및 인덱스를 정의한 물리 계층이다.

</details>

```text
[외부 스키마]
      |
[외부-개념 매핑]
      |
[개념 스키마]
      |
[개념-내부 매핑]
      |
[내부 스키마]
```

선의 의미: 외부-개념 매핑은 외부 스키마와 개념 스키마를 분리하고, 개념-내부 매핑은 개념 스키마와 내부 스키마를 분리해 인접 계층의 변경 영향을 흡수한다.

| 구성요소 | 책임 |
|:---|:---|
| 외부 스키마 | **외부 스키마**에 응용별 데이터 표현•뷰 정의 |
| 외부-개념 매핑 | **외부-개념 매핑**으로 외부 표현•개념 구조 변환 |
| 개념 스키마 | **개념 스키마**에 전체 개체•관계•제약 정의 |
| 개념-내부 매핑 | **개념-내부 매핑**으로 논리•물리 접근 경로 연결 |
| 내부 스키마 | **내부 스키마**에 파일•페이지•인덱스 정의 |

#### 한줄 요약

- 외부 스키마, 개념 스키마, 내부 스키마 사이에 두 단계의 매핑을 둔다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **데이터베이스 관리 시스템(Database Management System, DBMS) 매핑 계층**: 외부 뷰와 개념 구조 및 내부 저장 구조 사이의 변환을 수행하는 계층이다.
- **개념 질의•논리 연산 변환**: 외부 뷰 질의를 개념 구조의 연산으로 바꾸는 단계이다.
- **물리 접근 요청**: 개념 질의를 현재 저장 접근 경로에 대응시키는 단계이다.
- **내부 레코드 반환**: 내부 저장 구조에서 물리 데이터를 읽는 단계이다.
- **외부 뷰 결과 복원**: 레코드를 사용자별 표현으로 바꾸는 단계이다.

</details>

```text
외부 뷰 질의
      |
      v
1. 개념 질의•논리 연산 변환
      |
      v
2. 물리 접근 요청
      |
      v
3. 내부 레코드 반환
      |
      v
4. 외부 뷰 결과 복원
      |
      v
질의 결과 반환
```

### 동작 원리

- **1. 개념 질의•논리 연산 변환**: **DBMS 매핑 계층**의 **개념 질의•논리 연산 변환**으로 외부 뷰를 대응시킨다.
- **2. 물리 접근 요청**: **물리 접근 요청**으로 파일•페이지•인덱스를 조회한다.
- **3. 내부 레코드 반환**: **내부 레코드 반환**으로 물리 데이터를 전달한다.
- **4. 외부 뷰 결과 복원**: **외부 뷰 결과 복원**으로 사용자별 표현을 만든다.

#### 한줄 요약

- 외부 스키마와 내부 스키마 사이의 매핑이 변경된 저장 구조를 은닉하여 동일한 결과를 반환한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **호환 뷰**: 변경 전 외부 스키마를 기존 소비자에게 제공하는 뷰이다.
- **쓰기 호환성**: 구버전 쓰기를 새 개념 구조에 같은 의미로 반영하는 성질이다.
- **데이터 독립성 유형 선택 기준**: 변경 대상이 물리 저장인지 논리 개체•관계인지 구분하는 기준이다.

</details>

| 데이터 독립성 유형 | 물리적 독립성 | 논리적 독립성 |
|:---|:---|:---|
| 적용 기준 | 파일•페이지•인덱스 변경 | 테이블•관계•제약 변경 |
| 핵심 특징 | **물리 독립성**과 **개념-내부 매핑** | **논리 독립성**•**외부-개념 매핑**•**호환 뷰** |
| 한계 | 실행 계획•성능 회귀 가능 | 의미•**쓰기 호환성** 복잡성 |

> 요약: **데이터 독립성 유형 선택 기준**은 이름•단위•업무 의미 변경을 단순 뷰로 숨길 수 없음을 전제한다.

#### 한줄 요약

- 물리적 독립성은 저장 구조 변경을, 논리적 독립성은 개념 스키마 변경을 은닉한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **영향 계층**: 변경이 발생한 스키마 계층을 식별한 값이다.
- **보호 계약**: 기존 소비자에게 유지할 스키마와 동작 범위이다.
- **읽기 경로 검증**: 호환 뷰가 기존 조회 결과를 보존하는지 확인하는 활동이다.
- **쓰기 경로 검증**: 구버전 쓰기가 새 구조에 같은 의미로 반영되는지 확인하는 활동이다.
- **확장 후 축소**: 호환 구조를 먼저 추가하고 전환 뒤 옛 구조를 제거하는 방식이다.
- **버전 병행**: 소비자 전환 기간에 신구 스키마를 함께 운영하는 방식이다.
- **실행 계획**: 질의를 처리하는 물리 연산과 접근 순서이다.
- **95백분위 응답시간(95th Percentile Latency, p95)**: 요청의 95%가 완료되는 지연시간 기준이다.
- **자원량**: 처리에 소비되는 프로세서•메모리•입출력 규모이다.
- **전환 지표**: 구버전 소비자의 잔여 사용량을 나타내는 수치이다.
- **폐기 시점**: 호환 계층을 안전하게 제거할 날짜이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 변경 계층을 오분류하면 잘못된 매핑 밖으로 영향 전파 | **영향 계층**•**보호 계약** 명시 | 변경 책임 혼동 방지 |
| 호환 뷰의 읽기만 검증하면 쓰기 의미가 달라질 위험 | **읽기 경로 검증**•**쓰기 경로 검증** | 쓰기 의미 보존 |
| 즉시 스키마 교체는 구버전 소비자 요청 실패 유발 | **확장 후 축소**•**버전 병행** | 소비자 순차 전환 |
| 물리 구조 변경은 결과가 같아도 실행 계획 악화 가능 | **실행 계획**•**95백분위 응답시간**•**자원량** 비교 | 성능 회귀 탐지 |
| 호환 계층을 계속 유지하면 매핑 복잡도 누적 | **전환 지표**•**폐기 시점** 설정 | 호환 계층 누적 방지 |

#### 한줄 요약

- 번역표가 결과뿐 아니라 쓰기와 속도까지 유지하는지 확인해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **변경 격리**: 하위 계층 변경이 상위 계층으로 전파되지 않게 차단하는 원칙이다.
- **데이터 독립성 적용 기준**: 변경 계층과 보호할 상위 계약 및 담당 매핑을 함께 정하는 기준이다.

</details>

- **데이터 독립성 적용 기준**에 따라 저장 변경은 **개념-내부 매핑**, 논리 변경은 **외부-개념 매핑**에서 **변경 격리**한다.

#### 한줄 요약

- **데이터 독립성 적용 기준**은 어느 계층의 변화를 어떤 매핑이 맡을지 정한다.
