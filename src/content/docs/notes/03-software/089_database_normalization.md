## 미리 알고가기

- **정규화(Normalization)**: 함수 종속으로 릴레이션을 무손실 분해함
- **함수 종속성(Functional Dependency, FD)**: 결정자 값이 종속자 값을 유일하게 정함
- **완전 함수 종속(Full Functional Dependency)**: 종속자가 복합키 전체에만 종속됨
- **부분 함수 종속(Partial Functional Dependency)**: 종속자가 복합키 일부에 종속됨
- **이행 함수 종속(Transitive Functional Dependency)**: 키가 아닌 속성을 거쳐 종속됨
- **제1정규형(First Normal Form, 1NF)**: 각 속성을 원자값으로 구성함
- **제2정규형(Second Normal Form, 2NF)**: 비주요 속성의 부분 종속을 제거함
- **제3정규형(Third Normal Form, 3NF)**: 비주요 속성의 이행 종속을 제거함
- **보이스-코드 정규형(Boyce-Codd Normal Form, BCNF)**: 모든 결정자를 후보키로 제한함
- **온라인 트랜잭션 처리(Online Transaction Processing, OLTP)**: 정규화가 중요한 실시간 거래 처리임
- **결정자(Determinant)**: 함수 종속에서 다른 속성의 값을 유일하게 정하는 왼쪽 속성 집합임
- **종속자(Dependent)**: 결정자의 값에 따라 값이 정해지는 오른쪽 속성 집합임
- **후보키(Candidate Key)**: 모든 튜플을 유일하게 식별하는 최소 속성 집합임
- **비주요 속성(Non-prime Attribute)**: 어떤 후보키에도 포함되지 않는 속성임
- **무손실 조인 분해(Lossless-join Decomposition)**: 나눈 릴레이션을 자연 조인했을 때 거짓 튜플 없이 원본을 복원하는 분해임
- **종속성 보존(Dependency Preservation)**: 분해한 릴레이션만 검사해도 원래 함수 종속을 모두 강제할 수 있는 성질임
- **이상 현상(Anomaly)**: 중복 데이터 때문에 삽입·수정·삭제 시 의도하지 않은 불일치가 생기는 현상임
- **반정규화(Denormalization)**: 조회 성능을 위해 검증된 중복이나 결합 구조를 의도적으로 추가하는 설계임

## Ⅰ. 개요

- 정의/개념: 함수 종속을 기준으로 **릴레이션을 무손실 분해**하는 설계 기법
- 기존 한계: 중복 저장은 **삽입·갱신·삭제 이상·무결성 위반** 유발

### 쉽게 이해하기 (학습용)
- 고객 정보가 주문마다 반복되면 주소 수정이 일부에만 반영될 수 있어 고객과 주문을 분리함

## Ⅱ. 특징

- **함수 종속·후보키**로 변경 이상 원인 판정
- **무손실 분해**로 자연 조인 시 원본 릴레이션 복원
- **종속성 보존**으로 조인 없는 제약 검사 가능

### 쉽게 이해하기 (학습용)
- 정규화는 같은 사실을 한곳에 저장해 수정 오류를 줄이지만 조회할 때 여러 표를 다시 연결할 수 있음

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 함수 종속성(FD) | 결정자와 종속자의 값 제약을 표현함 |
| 후보키·결정자 | 최소 식별자와 종속의 왼쪽 속성을 구분함 |
| 무손실 분해 | 자연 조인으로 원래 릴레이션을 복원함 |
| 종속성 보존 | 분해된 릴레이션에서 원래 제약을 검사함 |

```text
  종속식별
      ↓
  결정분석
      ↓
  무손분해
      ↓
  종속검증
```

> 요약: 종속성과 후보키로 분해하고 무손실과 종속 보존을 검증함

### 쉽게 이해하기 (학습용)
- 속성 종속을 따라 표를 나누고 다시 합쳐 원본을 확인함

## Ⅳ. 원리 및 절차 흐름도

```text
  원자분리
      ↓
  부분제거
      ↓
  이행제거
      ↓
  결정검증
      ↓
  분해검증
```

| 절차 | 설명 |
|:---|:---|
| 원자값분리 | 1NF로 반복 속성을 원자값화함 |
| 부분종속제거 | 2NF로 복합키 일부 종속을 제거함 |
| 이행종속제거 | 3NF로 비주요 속성 간 종속을 제거함 |
| 결정자검증 | BCNF로 모든 결정자를 후보키화함 |
| 분해검증 | 무손실 조인과 종속 보존을 확인함 |

> 요약: 정규형별 종속을 제거하고 무손실 분해를 검증함

### 쉽게 이해하기 (학습용)
- 원자값부터 후보키 아닌 결정자까지 단계별로 분리함

## Ⅴ. 종류 및 비교

| 정규형 | 1NF·2NF | 3NF | BCNF |
|:---|:---|:---|:---|
| 적용 기준 | 반복값·부분 종속을 분리할 때 | 간접 종속을 분리할 때 | 남은 결정자 이상을 제거할 때 |
| 핵심 특징 | 원자값·**부분 종속 제거** | 비주요 속성의 **이행 종속 제거** | 모든 결정자의 **후보키화** |
| 한계 | 과도한 **테이블 분리** | 조인 증가·**질의 복잡화** | 업무 종속성 **오판** |

> 요약: 1NF부터 BCNF까지 다중값과 종속 이상을 순차 제거함

### 쉽게 이해하기 (학습용)
- 원자값과 부분 종속 및 결정자 이상을 차례로 제거함

## Ⅵ. 실무 사례

1. 신규 시스템은 **함수 종속·후보키**로 정규화

### 쉽게 이해하기 (학습용)
- 신규 거래 모델은 함수 종속으로 표를 나누고 다시 조인했을 때 원본과 같은지 확인해야 함

## Ⅶ. 결론

- **변경 이상·무손실성·종속성 보존** 검증 후 정규화

### 쉽게 이해하기 (학습용)
- 정규화는 중복과 변경 이상을 줄이는 논리 설계이며 반정규화는 측정된 조회 병목에 한해 검토해야 함
