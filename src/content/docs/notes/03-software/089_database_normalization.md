## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **함수적 종속성(Functional Dependency, FD)**: 어떤 속성 X의 값이 다른 속성 Y의 값을 유일하게 결정할 때 성립하는 관계 ($X \rightarrow Y$).
- **3대 이상 현상(Anomalies)**: 삽입 이상(불필요한 데이터 강제 입력), 갱신 이상(일부만 수정되어 불일치), 삭제 이상(필요한 정보까지 연쇄 삭제).

</details>

- 정의/개념: 데이터 중복을 최소화하고 3대 이상 현상을 방지하기 위해 **함수적 종속성(FD)에 따라 1NF부터 BCNF까지 릴레이션을 무손실 분해**하는 설계 기법
- 배경/필요성: 복수 엔티티 혼재로 인한 **데이터 중복, 3대 이상 현상(삽입·갱신·삭제 이상) 및 데이터 불일치 위험 한계**

#### 한줄 요약
- 정규화는 중복 저장 비용을 조인 연산 비용으로 옮기는 설계이므로, 단계를 올릴수록 갱신 이상은 줄지만 같은 결과를 얻는 데 필요한 릴레이션 결합 횟수는 함께 늘어난다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Lossless Join(무손실 조인 분해)**: 분해된 릴레이션들을 자연 조인했을 때 원래의 릴레이션과 100% 동일하게 복원되는 특성 (가짜 튜플 미발생).
- **Dependency Preservation(종속성 보존)**: 분해 후에도 원래 릴레이션의 모든 함수적 종속성이 보존되어 별도 조인 없이 무결성 검사가 가능한 성질.

</details>

- 데이터 중복을 최소화하여 **삽입·갱신·삭제 이상(3대 Anomaly) 원천 방지**
- 릴레이션 분해 후 자연 조인 시 데이터가 100% 복원되는 **무손실 조인 분해(Lossless Join) 보장**
- 함수적 종속성을 유지하여 제약 검증 비용을 줄이는 **종속성 보존(Dependency Preservation) 추구**

#### 한줄 요약
- 이상 현상 제거, 무손실 조인 분해, 종속성 보존의 3대 원칙을 준수한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정규화 4단계 요약**: 1NF(도메인 원자값) $\to$ 2NF(부분 함수 종속 제거) $\to$ 3NF(이행 함수 종속 제거) $\to$ BCNF(모든 결정자가 후보키).

</details>

```text
[데이터베이스 정규화 (1NF~BCNF)]
├─ [1NF (제1정규형)]
│  └─ 도메인 원자값화 (반복 그룹 제거)
├─ [2NF (제2정규형)]
│  └─ 완전 함수 종속화 (부분 함수 종속 제거)
├─ [3NF (제3정규형)]
│  └─ 직접 종속화 (이행적 함수 종속 제거)
└─ [BCNF (보이스-코드)]
   └─ 결정자 후보키화 (모든 결정자가 후보키)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 정규형 단계 | 대상 함수적 종속성 및 결함 | 분해 조치 및 핵심 달성 상태 |
|:---|:---|:---|
| 1NF (제1정규형) | 반복 그룹, 다중값(Multi-valued) 속성 | **모든 속성의 도메인을 단일 원자값(Atomic)으로 변환** |
| 2NF (제2정규형) | 복합 기본키의 일부에 종속 (**부분 함수 종속**) | 부분 종속 컬럼을 별도 테이블로 분리 (**완전 함수 종속**) |
| 3NF (제3정규형) | 기본키 경유 간접 종속 (**이행적 함수 종속: $X \to Y \to Z$)** | 종속 속성을 별도 엔터티로 분리하여 **직접 종속만 유지** |
| BCNF (보이스-코드) | 후보키가 아닌 속성이 타 속성을 결정 (**결정자 결함**) | **모든 결정자가 반드시 후보키(Candidate Key)가 되도록 분해** |

#### 한줄 요약
- 각 정규형은 앞 단계가 남긴 종속만 골라 제거하는 누적 구조여서 건너뛸 수 없으며, 마지막 BCNF에 이르면 이상 제거를 얻는 대신 종속성 보존을 포기해야 하는 경우가 생긴다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정규화 진행 알고리즘**: 복합키 식별 $\to$ 부분 종속 분해 $\to$ 일반 컬럼 간 종속 분해 $\to$ 결정자 후보키 판정.

</details>

```text
비정규 테이블 (예: 학생수강신청 {학번, 과목코드, 성적, 지도교수, 교수연구실})
        │
   [1NF 검사] 한 셀에 여러 과목이 들어간 반복 그룹을 단일 행으로 분리 (원자값화)
        │
   [2NF 검사] 복합키 {학번, 과목코드} 중 {과목코드} -> {과목명} 부분 종속 분리
        │
   [3NF 검사] {학번} -> {학과코드} -> {학과위치} 이행적 종속을 {학과} 테이블로 독립 분리
        │
   [BCNF 검사] {지도교수} -> {학과코드} 종속에서 지도교수가 후보키가 아니므로 분리
        │
   무손실 조인(Lossless Join) 및 종속성 보존(Dependency Preservation) 검증 후 물리 모델링
```

#### 한줄 요약
- 분해는 어느 단계에서 멈추든 무손실이라 원래 정보는 복원되지만 릴레이션 수만큼 조인 비용이 누적되므로, 어디서 멈출지를 정하는 것이 정규화의 실제 설계 판단이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **3NF vs BCNF**: 실무에서 종속성을 100% 보존하면서 조인 비용을 줄이는 3NF와 완벽한 결정자 무결성을 지향하는 BCNF.

</details>

| 비교 항목 | 3NF (제3정규형) | BCNF (보이스-코드 정규형) |
|:---|:---|:---|
| 핵심 요건 | 이행적 함수 종속($X \to Y \to Z$) 제거 | **모든 결정자가 슈퍼키(후보키)여야 함** |
| 종속성 보존 | **항상 함수적 종속성 100% 보존 가능** | 복합 후보키 중첩 시 종속성 보존 불가 가능 |
| 갱신 이상 방지 | 복합키 중첩 환경에서 일부 이상 잔존 | **결정자 결함으로 인한 이상 현상 완벽 차단** |
| 실무 적용성 | **대부분의 OLTP 상용 엔터프라이즈 표준** | 정밀 금융/결제 등 특수 정합성 요구 도메인 |

#### 한줄 요약
- 실무에서는 종속성 보존과 조인 성능을 고려하여 3NF를 표준으로 적용하고 필요 시 BCNF로 고도화한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Over-Normalization(과도한 정규화)**: 테이블이 지나치게 잘게 쪼개져 단순 화면 하나를 조회하는 데 10개 이상의 Join이 발생해 성능이 떨어지는 문제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 정규화로 인한 다중 Join 및 조회 TPS 급락 | **조회 빈도가 높은 테이블에 대해 전략적 반정규화(컬럼 중복, 집계 테이블)** | 디스크 I/O 절감 및 조회 속도 10배 향상 |
| BCNF 분해 시 함수적 종속성 보존 파괴 | **3NF 수준을 유지하고 애플리케이션 트랜잭션/트리거로 제약 검증** | 종속성 보존과 조인 성능의 균형 확보 |
| 릴레이션 분해 후 외래키 인덱스 누락으로 인한 Full Scan | **분해된 모든 Foreign Key(FK) 컬럼에 B-Tree 인덱스 필수 생성** | 조인 탐색 시간 $O(\log N)$ 보장 |
| 정규화 전후 스키마 불일치 | **ERD 데이터 모델링 툴(ERwin)을 통한 정방향/역방향 엔지니어링 동기화** | 논리-물리 모델 일치성 확보 |

#### 한줄 요약
- 전략적 반정규화, FK 인덱스 생성, 3NF 실무 절충, ERD 도구 동기화로 성능과 무결성을 양립한다.

## Ⅶ. 결론

- 엔터프라이즈 논리 데이터 모델링 및 OLTP 데이터베이스 설계의 **가장 기본적이고 핵심적인 무결성 보장 표준 원칙**으로 확립되었으며, 실무 프로젝트에서는 **함수적 종속성을 100% 보존하면서 조인 오버헤드를 억제하는 제3정규형(3NF)을 실무적 기준선으로 채택하고, 분해된 모든 외래키(FK)에 대한 B-Tree 인덱스 생성 및 대규모 조회 트래픽 병목 구간에 대한 선별적 반정규화(Denormalization)**를 결합하여 데이터 정합성과 응답 성능의 조화를 달성

#### 한줄 요약
- 정규화는 데이터 중복과 이상의 위험을 제거하는 논리 데이터 모델링의 절대 원칙이며, 3NF를 기본으로 한 물리 최적화가 핵심이다.
