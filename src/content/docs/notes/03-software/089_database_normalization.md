## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **함수적 종속성(Functional Dependency, FD)**: 어떤 속성 X의 값이 다른 속성 Y의 값을 유일하게 결정할 때 성립하는 관계($X \rightarrow Y$).
- **3대 이상 현상(Anomalies)**: 정규화 미비로 인해 릴레이션 조작 시 발생하는 삽입 이상(불필요 정보 강제 입력), 수정 이상(일부 튜플만 수정되어 불일치), 삭제 이상(원치 않는 유익 정보 연쇄 삭제).

</details>

- 정의/개념: 관계형 데이터베이스에서 데이터 중복을 최소화하고 무손실 분해를 달성하기 위해 **함수적 종속성(FD)에 따라 1NF부터 BCNF까지 릴레이션을 단계별 분해**하는 정형 설계 기법
- 배경/필요성: 비정규화된 단일 테이블 내 다중 사실 혼재로 인한 **삽입·수정·삭제 이상(Anomaly) 발생 및 데이터 불일치 위험** 직면

#### 한줄 요약

- 함수적 종속성을 기반으로 1NF에서 BCNF까지 단계별 무손실 분해를 수행하여 데이터 이상 현상을 원천 제거

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **무손실 조인 분해(Lossless Join Decomposition)**: 분해된 릴레이션들을 자연 조인했을 때 원래 릴레이션과 정확히 일치하며 유령 튜플(Spurious Tuple)이 생성되지 않는 성질.
- **종속성 보존(Dependency Preservation)**: 분해된 각 릴레이션의 함수적 종속성 집합의 합집합이 원래 릴레이션의 종속성 집합과 동등한 성질.

</details>

- 데이터 중복을 제거하여 **삽입·수정·삭제 이상(3대 Anomaly) 원천 방지**
- 기본키 및 외래키 기반의 **무손실 조인 분해(Lossless Join) 보장**
- 함수적 종속성을 유지하는 **종속성 보존(Dependency Preservation) 추구**

#### 한줄 요약

- 무손실 조인과 종속성 보존 원칙을 준수하며 테이블을 분해하여 데이터 무결성을 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **결정자 및 후보키(Determinant & Candidate Key)**: 함수적 종속성 $X \rightarrow Y$에서 $Y$를 결정하는 좌항 속성 $X$(결정자)와 릴레이션 내 튜플을 유일하게 식별하는 최소 집합(후보키).

</details>

```text
[ 데이터베이스 정규화 단계별 분해 구조도 ]

  [ 비정규 릴레이션 (다중값/반복그룹 존재) ]
               │
               ▼ (도메인 원자값화)
  [ 1NF (제1정규형) ] ──► 모든 속성이 단일 원자값(Atomic Value)으로만 구성
               │
               ▼ (부분 함수 종속성 제거: 완전 함수 종속화)
  [ 2NF (제2정규형) ] ──► 복합 기본키의 일부가 아닌 전체에 종속
               │
               ▼ (이행적 함수 종속성 제거: X -> Y -> Z 분해)
  [ 3NF (제3정규형) ] ──► 기본키가 아닌 속성 간의 종속 관계 제거
               │
               ▼ (결정자 중 후보키가 아닌 것 분해)
  [ BCNF (보이스-코드) ] ──► 모든 결정자가 반드시 후보키(Super Key)
```

선의 의미: 1NF부터 BCNF까지 이상 현상의 원인이 되는 함수적 종속성을 순차 제거하는 파이프라인.

| 구성요소 | 책임 |
|:---|:---|
| 1NF (제1정규형) | 반복 그룹(Repeating Group)을 제거하여 **모든 속성의 도메인을 원자값으로 구성** |
| 2NF (제2정규형) | 복합 기본키의 일부에 종속되는 **부분 함수 종속성을 제거하여 완전 함수 종속 달성** |
| 3NF (제3정규형) | $X \rightarrow Y \rightarrow Z$ 형태의 **이행적 함수 종속성을 제거하여 비주요 속성 분리** |
| BCNF (보이스-코드) | 후보키가 아닌 결정자($X$)를 분리하여 **모든 결정자가 후보키가 되도록 강제** |

#### 한줄 요약

- 원자값(1NF) $\to$ 완전함수종속(2NF) $\to$ 이행종속제거(3NF) $\to$ 결정자후보키화(BCNF)로 정규화 완성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정규화 판정 절차**: 릴레이션의 함수적 종속성 다이어그램을 작성하고 단계별 위반 요소를 찾아 분해하는 절차.

</details>

```text
[ 정규화 단계별 검증 및 분해 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 도메인 검사: 원자값 여부 판정 (1NF) │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 기본키 종속성: 부분 종속 분해 (2NF) │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 속성 간 종속성: 이행 종속 분해 (3NF)│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 결정자 검사: 비후보키 분해 (BCNF)   │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 무손실 조인 및 종속성 보존 최종 확인│
 └────────────────────────────────────────┘
```

### 동작 원리

1. 도메인 검사(1NF): 한 컬럼에 여러 값이 들어간 반복 그룹을 분리하여 단일 원자값으로 변환.
2. 기본키 종속성(2NF): 복합키 `{학번, 과목코드}`에서 `{학번} $\rightarrow$ 학과명`과 같은 부분 종속성을 별도 테이블로 분해.
3. 속성 간 종속성(3NF): `학번 $\rightarrow$ 학과코드 $\rightarrow$ 학과위치`의 이행적 종속성을 분해하여 `학과` 테이블을 독립 신설.
4. 결정자 검사(BCNF): 교수가 특정 과목을 가르치고 학생이 교수를 결정하는 구조에서 후보키가 아닌 결정자를 독립 분해.
5. 무손실 검증: 분해된 테이블 간의 자연 조인 결과가 원본과 일치하고 종속성이 유지되는지 검증.

#### 한줄 요약

- 1NF부터 BCNF까지 순차적으로 이상 원인을 제거하고 무손실 조인 및 종속성 보존을 확인

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **3NF vs BCNF**: 대부분의 비즈니스 종속성을 보존하면서 조인 비용을 억제하는 3NF와 완벽한 결정자 무결성을 달성하는 BCNF.

</details>

| 구분 | 3NF (제3정규형) | BCNF (보이스-코드 정규형) |
|:---|:---|:---|
| **적용 기준** | 일반적인 OLTP 상용 엔터프라이즈 시스템 | 높은 데이터 무결성이 요구되는 복합 후보키 시스템 |
| **핵심 특징** | **이행적 함수 종속 제거 및 항상 종속성 보존 가능** | **모든 결정자가 후보키이며 강력한 이상 현상 방지** |
| **한계** | 복합 후보키 간 중첩 시 일부 갱신 이상 잔존 가능 | 분해 과정에서 기존 함수적 종속성 보존 불가 가능 |

#### 한줄 요약

- 실무에서는 종속성 보존과 조인 성능을 고려하여 3NF를 표준으로 적용하고 필요시 BCNF로 고도화

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **과도한 정규화(Over-Normalization)**: 지나친 테이블 분해로 인해 잦은 다중 조인(Multi-Join)이 발생하여 데이터베이스 I/O 및 CPU 부하가 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지나친 정규화로 인한 다중 조인(JOIN) 및 조회 TPS 저하 | **조회 빈도가 높은 테이블에 대한 전략적 반정규화(Denormalization)** | 디스크 I/O 절감 및 조회 응답속도 향상 |
| BCNF 분해 시 종속성 보존(Dependency Preservation) 파괴 | **3NF 수준을 유지하고 애플리케이션 트랜잭션/트리거로 제약 검증** | 종속성 보존과 성능의 균형 확보 |
| 릴레이션 분해 후 외래키 인덱스 부재로 조인 지연 | **분해된 모든 Foreign Key(FK) 컬럼에 B-Tree 인덱스 필수 생성** | 조인 탐색 시간 $O(\log N)$ 보장 |

#### 한줄 요약

- 전략적 반정규화, 애플리케이션 제약 보완, FK 인덱스 생성을 통해 정규화의 성능 저하를 방어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **논리-물리 모델링 전이(Logical to Physical Modeling)**: 3NF/BCNF 정규화로 논리적 무결성을 완성한 후, 물리 설계 단계에서 트래픽 특성에 맞추어 반정규화 및 인덱스를 최적화하는 절차.

</details>

- **데이터베이스 정규화** 기반 데이터 중복과 이상의 위험을 제거하는 논리 데이터 모델링의 기본 원칙이며, 실무에서는 3NF 수준의 정규화를 기본으로 구축한 후 시스템 성능 요구에 맞추어 전략적 반정규화를 적용해야 함

#### 한줄 요약

- 3NF/BCNF 정규화로 데이터 무결성을 확보하고 물리 설계에서 인덱스와 반정규화로 성능을 최적화
