## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 패브릭(Data Fabric)**: 온프레미스, 클라우드, 멀티 클라우드에 분산된 이종 데이터 원천들을 물리적 복제 없이 Active Metadata, 지식 그래프(Knowledge Graph), AI/ML 자동화를 통해 유연하게 직조(Fabric)하여 실시간 가상 통합을 제공하는 아키텍처.
- **활성 메타데이터(Active Metadata)**: 수동 등록에 의존하지 않고 쿼리 패턴, 사용자 접근 로그, 파이프라인 성능을 AI로 실시간 지속 분석하여 데이터 관리와 추천에 능동 반영하는 메타데이터.

</details>

- 정의/개념: 분산된 이종 데이터 환경에서 **Active Metadata와 지식 그래프 및 데이터 가상화를 통해 데이터를 물리적 이동 없이 실시간 통합·제공**하는 지능형 데이터 아키텍처
- 배경/필요성: 하이브리드·멀티 클라우드 확산으로 인한 **데이터 고립(Silo), 메타데이터 수동 관리 한계 및 전사 데이터 계보 추적 불가 위험** 직면

#### 한줄 요약

- 활성 메타데이터와 데이터 가상화를 통해 물리적 데이터 이동 없이 이종 멀티 클라우드 데이터를 단일 패브릭으로 통합

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 가상화(Data Virtualization)**: 물리적인 ETL 복제 없이 이종 데이터베이스의 테이블을 실시간 가상 뷰(Virtual View)로 결합하여 단일 SQL로 쿼리하는 기술.
- **지식 그래프(Knowledge Graph)**: 데이터 자산 간의 의미론적 관계, 계보(Lineage), 스키마, 사용자 접근 이력을 노드와 엣지로 시각화하고 AI 추천을 제공하는 구조.

</details>

- AI/ML 기반으로 사용자 패턴과 성능을 지속 학습하는 **Active Metadata 기반 자동화**
- 물리적 복제 없이 분산 원천을 단일 SQL로 조회하는 **데이터 가상화(Data Virtualization)**
- 분산 저장소 전반에 일관된 PII 마스킹과 접근 제어를 적용하는 **통합 거버넌스 집행**

#### 한줄 요약

- 활성 메타데이터와 지식 그래프를 활용하여 복잡한 분산 데이터 파이프라인의 수동 운영 부담을 자동화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상화 및 오케스트레이션 레이어**: Trino/Denodo 기반의 데이터 가상화 엔진과 Airflow/Prefect 기반의 데이터 파이프라인 제어 계층.

</details>

```text
[ 데이터 패브릭(Data Fabric) 계층 아키텍처 구조도 ]

 ┌────────────────────────────────────────────────────────────────────────┐
 │ 1. 데이터 소비 계층: [ BI Analytics ]  [ Data Science / ML ]  [ Apps ]│
 ├────────────────────────────────────────────────────────────────────────┤
 │ 2. Active Metadata & Knowledge Graph 레이어                             │
 │   - 실시간 접근 로그 분석, AI 추천 카탈로그, 전사 데이터 리니지(Lineage)│
 ├────────────────────────────────────────────────────────────────────────┤
 │ 3. 데이터 가상화 및 오케스트레이션 레이어 (Trino / Denodo / Airflow)   │
 │   - 물리적 이동 없는 분산 쿼리 푸시다운, 결과 캐싱, 파이프라인 자동화 │
 ├────────────────────────────────────────────────────────────────────────┤
 │ 4. 하이브리드 멀티 클라우드 원천 (AWS S3, Snowflake, Oracle, MySQL)   │
 └────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 이종의 멀티 클라우드 소스 데이터를 Active Metadata 및 가상화 레이어를 거쳐 단일 패브릭으로 묶어 비즈니스 소비자에게 제공하는 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 원천 (Data Sources) | 하이브리드 멀티 클라우드 상의 **RDBMS, DW, Data Lake 데이터 제공** |
| Active Metadata 엔진 | 실시간 쿼리 및 접근 패턴을 감지하여 **데이터 추천 및 파이프라인 자동 최적화** |
| 지식 그래프 (Knowledge Graph) | 전사 데이터 간의 **의미론적 연관 관계, 스키마 계보(Lineage), 소유권 매핑** |
| 가상화 엔진 (Virtualization) | 분산 원천 데이터에 대한 **단일 SQL 인터페이스 및 조건절 푸시다운 수행** |
| 정책 엔진 (Policy Engine) | 역할 기반(RBAC) 및 속성 기반(ABAC) **통합 보안/PII 마스킹 정책 자동 강제** |

#### 한줄 요약

- 원천 데이터, Active Metadata, 지식 그래프, 가상화 엔진, 정책 엔진이 유기적으로 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 패브릭 가상 통합 5단계 절차**: 데이터 자산 탐색 $\to$ 정책/권한 검증 $\to$ 최적 실행 계획 $\to$ 가상 쿼리 푸시다운 $\to$ 피드백 메타 반영.

</details>

```text
[ Data Fabric 지능형 가상화 쿼리 파이프라인 ]

 ┌────────────────────────────────────────┐
 │ 1. 사용자 쿼리 접수 및 지식그래프 탐색│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 2. 정책 엔진: ABAC 권한 판정 및 마스킹│
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 3. 최적 실행 계획 수립 (비용 기반 계산) │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 4. 분산 원천 DB 조건절 푸시다운 & 캐싱 │
 └───────────────────┬────────────────────┘
                     │
                     ▼
 ┌────────────────────────────────────────┐
 │ 5. 쿼리 성능 신호 ➔ Active Metadata 피드백
 └────────────────────────────────────────┘
```

### 동작 원리

1. 자산 탐색: 클라이언트의 자연어 또는 SQL 요청 시 지식 그래프와 카탈로그를 참조하여 타깃 데이터 자산을 자동 매핑.
2. 정책 판정: 정책 엔진이 사용자의 직무와 접근 목적을 검증하고 민감정보(PII)를 실시간 동적 마스킹 처리.
3. 실행 계획 수립: 가상화 옵티마이저가 네트워크 I/O 비용과 각 DB 엔진의 연산 부하를 계산하여 최적 분산 실행 계획을 수립.
4. 가상 쿼리 실행: 원천 DB들로 조건절을 푸시다운(Predicate Pushdown)하여 로컬 연산 후 결과만 메모리로 취합 반환.
5. 메타 피드백: 쿼리 응답 시간, 캐시 적중률 등의 실행 통계를 Active Metadata 엔진에 피드백하여 차후 쿼리 계획을 자동 보정.

#### 한줄 요약

- 자산 탐색 $\to$ 권한/마스킹 판정 $\to$ 계획 수립 $\to$ 푸시다운 실행 $\to$ 메타데이터 피드백의 5단계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전통적 ETL vs 데이터 패브릭**: 물리적 대용량 복제 방식의 ETL과 Active Metadata 기반 실시간 가상화 통합 방식의 데이터 패브릭.

</details>

| 구분 | 전통적 ETL / Data Warehouse | 데이터 패브릭 (Data Fabric) |
|:---|:---|:---|
| **적용 기준** | 단일 스토리지 중심의 정형 BI 분석 환경 | 하이브리드 멀티 클라우드에 분산된 이종 데이터 통합 환경 |
| **핵심 특징** | **물리적 데이터 일괄 복제(Batch ETL), 정적 메타데이터** | **Active Metadata 기반 AI 자동화, 데이터 가상화(0회 이동)** |
| **한계** | 파이프라인 구축 수개월 소요 및 스토리지 중복 비용 | 이종 DB 간 대규모 조인 시 네트워크 지연시간 발생 |

#### 한줄 요약

- 물리적 일괄 복제는 전통적 ETL, 분산 원천의 실시간 지능형 통합은 데이터 패브릭을 채택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가상화 조인 네트워크 지연(Cross-Cloud Latency)**: 물리적 복제 없이 서로 다른 클라우드(AWS vs Azure) 간 대용량 조인 시 네트워크 대역폭 한계로 쿼리가 지연되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이종 클라우드 DB 간 가상화 `JOIN` 시 네트워크 지연 급증 | **Trino 조건절 푸시다운(Pushdown) 및 빈번 쿼리 가상 캐싱 적용** | 네트워크 전송 데이터량 90% 절감 |
| 메타데이터 갱신 지연으로 인한 낡은(Stale) 매핑 정보 조회 | **Debezium CDC 기반 실시간 스키마/메타데이터 동기화 훅 설정** | 메타데이터 최신성 100% 보장 |
| 멀티 클라우드 환경에서 이종 IAM 보안 정책 불일치 | **Immuta / Privacera 등 중앙 데이터 거버넌스 플랫폼 도입** | 단일 보안 정책으로 전사 일관 통제 |

#### 한줄 요약

- 조건절 푸시다운, CDC 메타 동기화, 통합 거버넌스 도입을 통해 데이터 패브릭의 실시간성을 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **패브릭과 메시의 상호 보완(Fabric-Mesh Synergy)**: Data Fabric의 가상화·메타데이터 기술 인프라 위에 Data Mesh의 도메인 제품 소유권을 얹어 전사 데이터 플랫폼을 완성하는 전략.

</details>

- **데이터 패브릭** 분산된 멀티 클라우드 환경에서 데이터 물리 이동 없이 지능형 통합을 실현하는 차세대 아키텍처이며, Active Metadata와 데이터 가상화를 기반으로 기업의 데이터 분석 민첩성을 극대화해야 함

#### 한줄 요약

- Active Metadata와 지식 그래프를 기반으로 분산 데이터를 가상화 통합하여 지능형 데이터 플랫폼을 완성
