## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **유닉스(UNIX)**: 커널•셸•파일 시스템의 책임을 분리하고 다중 사용자를 지원하는 운영체제 계열이다.
- **특권 접근**: 하드웨어와 핵심 자원을 직접 제어할 수 있도록 커널에 제한된 실행 권한이다.

</details>

- 정의/개념: 커널•셸•파일 시스템의 책임과 경계를 분리한 **UNIX 운영체제 구조**이다.
- 배경/필요성: 응용의 직접 특권 접근은 **자원 충돌•권한 침해**를 유발한다.

#### 한줄 요약

- 셸•커널•파일 시스템의 **명령•자원•저장 책임 분리**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **시스템 호출(System Call)**: 사용자 프로그램이 커널의 프로세스•메모리•장치 기능을 요청하는 인터페이스다.
- **파이프(Pipe)**: 한 프로세스의 출력을 다른 프로세스의 입력에 연결하는 통신 방식이다.
- **파일 시스템(File System)**: 파일•디렉터리의 경로•권한•저장 블록을 관리하는 운영체제 계층이다.

</details>

- **커널 시스템 호출**로 프로세스•메모리•장치를 통제한다.
- **셸 명령 해석•파이프**로 단일 기능 프로그램 조합이 핵심이다.
- **파일 시스템 계층**으로 경로•권한•영속 블록을 관리한다.

#### 한줄 요약

- 시스템 호출과 **명령 조합•파이프** 기반을 처리한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **셸(Shell)**: 사용자 명령을 해석해 커널에 프로세스 실행을 요청하는 프로그램이다.
- **커널(Kernel)**: 특권 모드에서 프로세스•메모리•장치 자원을 통제하는 운영체제 핵심이다.

</details>

```text
[셸] -------- [커널] -------- [파일 시스템]
```

선의 의미: 셸과 커널의 선은 명령을 시스템 호출로 요청하는 관계, 커널과 파일 시스템의 선은 경로•권한•저장 블록을 특권 경계에서 관리하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 셸 | **명령 해석•실행 조합** |
| 커널 | **특권 자원 통제** |
| 파일 시스템 | **경로•권한•블록 관리** |

#### 한줄 요약

- 셸•커널•파일 시스템의 **3계층 책임 구조**가 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **명령 해석**: 셸이 명령•인수•파이프를 실행 단위로 구성하는 단계다.
- **프로세스 실행 요청**: 셸이 시스템 호출로 커널에 프로그램 실행을 요구하는 단계다.
- **경로•권한 조회**: 파일 시스템에서 실행 파일의 메타데이터와 권한을 확인하는 단계다.
- **프로세스 생성•실행**: 커널이 주소 공간과 자원을 배정해 프로그램을 수행하는 단계다.
- **종료 상태 처리**: 셸이 완료 코드를 받아 분기•파이프 결과를 결정하는 단계다.

</details>

```text
┌──────────────────────────────┐
│ 사용자 명령•인수           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 명령 해석               │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 프로세스 실행 요청      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 경로•권한 조회          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 프로세스 생성•실행      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 종료 상태 처리          │
└──────────────┬───────────────┘
               ▼
          [실행 결과 출력]
```

**동작 원리**

- **1. 명령 해석**: 명령•인수•파이프 실행 단위를 구성한다.
- **2. 프로세스 실행 요청**: 시스템 호출로 커널 기능 진입이다.
- **3. 경로•권한 조회**: 실행 파일 위치•권한을 확인한다.
- **4. 프로세스 생성•실행**: 주소 공간•자원 배정 후를 수행한다.
- **5. 종료 상태 처리**: 완료 코드를 분기•파이프에 반영한다.

#### 한줄 요약

- 명령 해석부터 종료 상태까지 **3요소 실행 흐름**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>


</details>

| UNIX 구성요소 | 맡는 경계 | 핵심 처리 |
|:---|:---|:---|
| **커널** | 프로세스•메모리•장치의 특권 경계 | 시스템 호출에 따른 **자원•권한 통제** |
| **셸** | 사용자 명령과 프로그램 실행 경계 | 명령 해석•**프로세스•파이프 구성** |
| **파일 시스템** | 파일 이름과 저장 블록의 영속 경계 | 경로•권한•**메타데이터 관리** |

> 요약: 셸의 요청을 커널이 통제하고 파일 시스템이 **영속 상태**를 보관이 핵심이다.

#### 한줄 요약

- 커널은 자원, 셸은 명령, **파일 시스템은 저장** 담당이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **허용 목록(Allowlist)**: 실행을 허용한 명령과 인수만 명시하고 그 밖의 입력을 거부하는 목록이다.
- **최소 권한(Least Privilege)**: 작업에 필요한 최소한의 사용자•파일•장치 권한만 부여하는 원칙이다.
- **권한 비트(Permission Bits)**: 소유자•그룹•기타 사용자의 읽기•쓰기•실행 허용 여부를 기록하는 값이다.
- **파이프 실패 전파(Pipeline Failure Propagation)**: 연결한 명령 중 하나의 실패를 전체 작업의 종료 상태로 전달하는 처리다.
- **명령 주입(Command Injection)**: 신뢰하지 않은 입력이 셸 명령이나 인수로 해석되어 의도하지 않은 프로그램이 실행되는 취약점이다.
- **변경 감사(Change Audit)**: 파일 권한이나 소유자 변경 이력을 기록해 누가 언제 무엇을 바꿨는지 확인하는 통제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신뢰하지 않은 입력을 셸 문법으로 해석해 **명령 주입** | **인수 분리•허용 목록** 적용 | 의도하지 않은 **명령 실행** 방지 |
| 셸•서비스를 과도한 권한으로 실행해 **침해 범위** 확대 | 전용 사용자와 **최소 권한** 적용 | 사용자•파일•장치의 **피해 범위** 제한 |
| 소유자•권한 비트 오류로 **민감 파일 노출** | **기본 권한 정책•변경 감사** 적용 | 무단 **읽기•변경** 방지 |
| 파이프 중간 실패를 최종 성공으로 오인해 **후속 작업 실행** | **파이프 실패 전파•종료 상태** 기록 | 자동화 작업의 **오류 조기 탐지** |

#### 한줄 요약

- 인수 분리•최소 권한•**실패 상태 전파**를 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **책임 분리**: 명령 해석•특권 자원•영속 데이터 관리를 셸•커널•파일 시스템에 각각 맡기는 구조 원칙이다.

</details>

- **UNIX**에서 사용자 명령은 셸, 특권 자원은 커널, 영속 데이터는 **파일 시스템**으로 책임을 분리한다.

#### 한줄 요약

- 명령•특권 자원•영속 데이터의 **책임 경계 유지**가 핵심이다.
