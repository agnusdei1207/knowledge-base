## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **UNIX 3대 구성요소(UNIX Architecture)**: 멍청한 기계(하드웨어)와 인간을 이어주기 위해, 껍데기(쉘), 알맹이(커널), 창고(파일 시스템)로 철저하게 역할을 찢어놓은 근본 아키텍처이다.
- **커널(Kernel)**: 하드웨어 멱살을 잡고 메모리, CPU 스케줄링 등 시스템의 궂은일을 도맡아 하는, 사용자 접근 금지 구역(Kernel Mode)의 절대 권력자이다.
- **쉘(Shell)**: 사용자가 키보드로 치는 외계어를 해석해서 커널이 알아듣게 전달해 주는 까탈스러운 비서이자 명령어 해석기이다.

</details>

- 정의: 하드웨어 자원을 꽁꽁 숨기고, 사용자 명령 처리(Shell), 핵심 제어(Kernel), 데이터 영구 보관(File System)으로 역할을 칼같이 나눈 **UNIX 3대 아키텍처**
- 배경: 응용 프로그램이 지 맘대로 하드웨어를 건드리면 시스템이 뻑나니까, **접근 권한을 분리**하고 파이프라인으로 명령을 조립하기 위함

#### 한줄 요약

- 사용자의 명령을 받는 쉘, 기계를 통제하는 커널, 데이터를 저장하는 파일 시스템 3대장 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스템 콜(System Call)**: 사용자가 커널의 VIP 구역 자원(하드웨어)을 쓰고 싶을 때, 예의 바르게 허락을 구하며 호출하는 OS 전용 인터페이스(트랩)이다.
- **모든 것은 파일이다(Everything is a File)**: 키보드, 모니터, 네트워크 소켓까지 싹 다 '파일'이라는 하나의 개념으로 퉁쳐버려서, 입출력 방식을 극단적으로 단순화한 UNIX의 미친 철학이다.

</details>

- 사용자가 뒹구는 **유저 공간(User Space)**과 절대 권력의 **커널 공간(Kernel Space)**을 철통같이 분리함.
- **Everything is a File** 철학으로 복잡한 장치들을 파일 하나로 퉁쳐서 추상화함.
- 단순한 명령어들을 **파이프(`|`)**로 엮어서 거대한 작업을 처리하는 모듈식 조합의 끝판왕임.

#### 한줄 요약

- 커널과 유저 공간을 분리하고, 모든 걸 파일로 취급하며, 파이프로 명령을 조립하는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **POSIX 표준(POSIX Standard)**: "유닉스 계열이면 코드 좀 똑같이 쓰자"라고 멱살 잡고 통일시킨 IEEE의 운영체제 인터페이스 국제 룰이다.

</details>

```text
[ UNIX 3계층 십자포화 아키텍처 ]
         [ 사용자 (User) ]
                │ (명령어 입력)
         [ 쉘 (Shell) ]
      (명령어 해석 및 파이프 조립)
                │ (시스템 콜 찌름)
┌───────────────▼───────────────┐
│          [ 커널 (Kernel) ]    │
│ (CPU/메모리 스케줄링, 하드웨어 통제)│
└───────────────┬───────────────┘
                ▼
      [ 파일 시스템 (File System) ]
     (모든 데이터를 파일로 영속 저장)
```

| 구성요소 | 책임 |
|:---|:---|
| 쉘 (Shell) | 사용자의 타건을 해석하고, 프로그램들을 **파이프(`\|`)**로 엮어서 커널에 던지는 번역기 |
| 커널 (Kernel) | 쉘이 던진 **시스템 콜**을 받아 CPU와 메모리를 할당하고 하드웨어를 직접 조지는 심장 |
| 파일 시스템 | "모든 것은 파일" 철학에 따라 진짜 파일부터 장치 파일까지 싹 다 관리하는 영속성 창고 |

#### 한줄 요약

- 사용자가 쉘에 명령을 치면, 쉘이 시스템 콜로 커널을 찌르고, 커널이 파일 시스템과 하드웨어를 굴린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **fork() / exec()**: 쉘이 새 프로그램을 띄울 때, 자기 자신을 똑같이 복제(`fork`)한 다음, 그 껍데기에 새 프로그램의 뇌를 덮어씌워(`exec`) 실행하는 UNIX 특유의 기괴한 기동 방식이다.

</details>

```text
[ UNIX 쉘-커널 명령 실행 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 사용자 명령어 입력        │
│ (ls -al | grep log)          │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 쉘 명령 해석 및 분해      │
│ (파이프/옵션 파싱)           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 프로세스 복제 (fork)      │
│ (쉘이 자기 자신을 쪼갬)      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 커널 권한 획득 및 실행(exec)│
│ (진짜 바이너리를 덮어씌워 돌림)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 종료 및 프롬프트 복귀     │
│ (wait()로 결과값 회수)       │
└──────────────────────────────┘
```

### 동작 원리

1. 명령어 입력: 사용자가 쉘 프롬프트에 키보드로 명령어를 갈김.
2. 명령 해석: 쉘이 명령어를 뜯어보고 파이프나 리다이렉션(`>`, `<`)을 세팅함.
3. 프로세스 복제: 쉘이 **fork()** 시스템 콜을 때려 자식 프로세스를 복제함.
4. 실행 덮어쓰기: 복제된 자식에 **execve()**를 쏴서 진짜 바이너리를 덮어씌우고 커널이 CPU를 할당함.
5. 종료 대기 및 복귀: 쉘은 **waitpid()**로 자식이 죽을 때까지 기다리다가, 결과를 받고 프롬프트를 다시 띄움.

#### 한줄 요약

- 명령을 해석하고, fork로 몸통을 쪼갠 뒤, exec로 뇌를 갈아 끼워서 프로그램을 실행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모놀리식 커널 vs 마이크로 커널(Monolithic vs Microkernel)**: 모놀리식은 OS의 모든 기능(네트워크, 파일, 드라이버)을 뚱뚱한 커널 하나에 다 때려 박은 깡성능 위주 방식이고, 마이크로 커널은 핵심만 남기고 싹 다 밖으로 빼버린 모듈형 방식이다.

</details>

| 비교 항목 | 쉘 (Shell) | 커널 (Kernel) | 파일 시스템 (File System) |
|:---|:---|:---|:---|
| 실행 공간 | 권한이 1도 없는 **유저 공간(User Space)** | 신성불가침의 **커널 공간(Ring 0)** | 커널 공간 안에서 디스크를 쥐고 흔듦 |
| 주 활동 무대 | 메모리(RAM) 유저 스택 영역 | 메모리(RAM) 핵심 커널 영역 | 진짜 물리 디스크(HDD/SSD) 구역 |
| 유저 접근성 | 사용자가 키보드로 직접 치고받는 접점 | 사용자는 절대 직접 못 만짐 (**시스템 콜** 필수) | 쉘이 명령을 내려야만 비로소 열리는 창고 |

#### 한줄 요약

- 쉘은 껍데기 유저 공간에서 놀고, 커널은 코어 메모리에서 절대 권력을 쥐며, 파일 시스템은 디스크를 팬다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쉘 인젝션(Shell Injection)**: 웹 서버 같은 데서 입력값 검증을 대충 했을 때, 해커가 `; rm -rf /` 같은 악성 쉘 명령어를 끼워 넣어 서버를 통째로 날려버리는 고전적인 해킹 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 해커가 입력창에 `;`나 `\|`를 섞어서 **쉘 인젝션** 공격을 꽂아버림 | 입력값을 무조건 텍스트로 치환하고 허용 목록 컷침 | 의도치 않은 파멸적 쉘 명령 실행 원천 차단 |
| 멍청한 유저 프로그램이 하드웨어를 직접 건드려서 서버가 뻗어버림 | **User / Kernel Mode**를 칼같이 분리해 특권 틀어막음 | 찌끄레기 프로그램이 죽어도 OS 전체는 무사함 |
| `while true; do fork; done` (포크 폭탄) 돌려서 서버 램 100% 찍고 죽음 | 리눅스 **ulimit** 설정으로 유저당 최대 프로세스 수 멱살 잡음 | PID/메모리 고갈로 서버가 뻗는 대참사 방지 |

#### 한줄 요약

- 쉘 인젝션은 특수문자 필터링으로 막고, 시스템 크래시는 커널 모드로 막고, 포크 폭탄은 ulimit으로 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **UNIX 아키텍처 설계 기준(UNIX Architecture Standards)**: "역할은 찢고, 표준은 지키며, 철학은 유지한다"는 유닉스 50년 짬바의 아키텍처 잣대이다.

</details>

- **UNIX 아키텍처 설계 기준** 원칙에 따라, 사용자 인터페이스는 **쉘**, 코어 제어는 **커널**, 데이터 보존은 **파일 시스템**으로 철저히 격리하는 3대 역할 분담 기조 확립함

#### 한줄 요약

- 커널, 쉘, 파일 시스템의 역할과 권한을 완벽하게 찢어놓은 게 유닉스의 성공 비결이다.
