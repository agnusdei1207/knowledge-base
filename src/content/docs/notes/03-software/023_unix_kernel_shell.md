## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **쉘, 커널, VFS(Shell, Kernel, VFS)**: 사용자 명령 인터페이스(쉘), 특권 제어 및 하드웨어 추상화 계층(커널), 모든 객체를 파일로 추상화하는 계층형 파일시스템.
- **시스템 충돌 및 이식성 부재(System Crash & Portability Loss)**: 비보호 모드에서 응용 프로그램의 메모리 오염이 OS 전체 다운을 유발하고 비표준 API로 이식이 불가능한 한계.

</details>

- 정의/개념: 사용자 명령을 해석하는 **쉘(CLI)** 과 자원을 관리하는 **커널(Core)** 및 계층형 **VFS(파일시스템)** 로 구성된 모듈형 운영체제 구조
- 배경/필요성: 응용 프로그램의 하드웨어 직접 접근 시 발생하는 **시스템 전체 충돌 위험 및 OS 간 이식성 부재** 직면

#### 한줄 요약

- 사용자 명령을 받는 쉘, 하드웨어를 제어하는 커널, 데이터를 저장하는 파일 시스템의 3계층 역할 분리 구조

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스템 콜(System Call)**: 사용자 공간의 프로그램이 커널 공간의 자원·서비스에 접근하기 위해 호출하는 운영체제 공식 인터페이스.
- **Everything is a File**: 파일·장치·소켓·파이프를 모두 파일 디스크립터로 통일하여 단일 I/O 추상화 체계로 제공하는 UNIX 설계 철학.

</details>

- 사용자 공간(**User Space**)과 커널 공간(**Kernel Space**)의 엄격한 분리로 시스템 안정성 확보
- **Everything is a File** 철학으로 장치·소켓 등을 파일 추상화로 통일
- 단순 명령어를 **파이프(`|`)** 로 조합하여 복잡한 작업을 처리하는 모듈형 설계

#### 한줄 요약

- 커널·유저 공간을 분리하고 모든 자원을 파일로 추상화하며 파이프로 명령을 조합하는 UNIX 핵심 설계

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **POSIX 표준**: IEEE가 제정한 UNIX 계열 운영체제의 시스템 인터페이스 표준으로, POSIX 준수 프로그램의 운영체제 간 이식성을 보장.

</details>

```text
[ UNIX 3계층 구조 ]
사용자 (User)
   │ 명령어 입력
   ▼
쉘 (Shell)
├─ 명령어 해석·파이프·리다이렉션 처리
└─ 시스템 콜 호출
커널 (Kernel) [Kernel Space / Ring 0]
├─ 프로세스 스케줄링·메모리 관리
├─ 하드웨어 드라이버 제어
└─ 파일 시스템 인터페이스
파일 시스템 (File System)
└─ 파일·장치·소켓을 파일 추상화로 영속 관리
```

선의 의미: 가지(`├─`, `└─`)는 각 계층의 책임 범위와 상위 계층으로부터의 요청 수신 관계

| 구성요소 | 책임 |
|:---|:---|
| 쉘 | 사용자 명령 해석·파이프 세팅·**시스템 콜** 호출 |
| 커널 | **시스템 콜** 수신·하드웨어 자원 제어·프로세스 관리 |
| 파일 시스템 | **Everything is a File** 기반 파일·장치·소켓 영속 관리 |

#### 한줄 요약

- 쉘이 명령을 해석하여 시스템 콜로 커널을 호출하고, 커널이 파일 시스템과 하드웨어를 제어

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **fork() / exec()**: 쉘이 새 프로세스를 생성할 때 자신을 복제(fork)하고 대상 프로그램의 이미지로 교체(exec)하는 UNIX 프로세스 기동 방식.

</details>

```text
사용자 명령어 입력 (예: ls -al | grep log)
   │
   ▼
1. 쉘: 명령어 파싱 및 파이프·리다이렉션 세팅
   │
   ▼
2. fork(): 자식 프로세스 생성 (쉘 상태 복제)
   │
   ▼
3. exec(): 자식 프로세스 이미지를 대상 바이너리로 교체
   │
   ▼
4. 커널: 시스템 콜 처리·CPU·메모리 할당·파일 시스템 접근
   │
   ▼
5. wait(): 쉘이 자식 종료 대기 후 결과 수신 → 프롬프트 복귀
```

**동작 원리** 1. **명령 파싱**: 쉘이 입력 명령어를 파싱하여 파이프·리다이렉션 연결을 구성
2. **fork()**: 쉘이 자신을 복제한 자식 프로세스를 생성
3. **exec()**: 자식 프로세스가 대상 바이너리로 프로세스 이미지를 교체
4. **커널 실행**: 커널이 CPU를 할당하고 파일 시스템·장치에 접근하여 명령을 실행
5. **wait() 종료**: 쉘이 자식 프로세스 종료를 대기하고 종료 코드를 수신

#### 한줄 요약

- 쉘이 명령을 파싱하고 fork/exec로 자식 프로세스를 기동하면 커널이 자원을 할당하여 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모놀리식 커널 vs 마이크로커널(Monolithic vs Microkernel)**: 모놀리식은 네트워크·파일·드라이버를 모두 커널 공간에 통합하여 성능을 높이는 방식이고, 마이크로커널은 핵심 기능만 커널에 두고 나머지를 사용자 공간 서버로 분리하는 방식.

</details>

| 구분 | 쉘 (Shell) | 커널 (Kernel) | 파일 시스템 |
|:---|:---|:---|:---|
| 실행 공간 | **유저 공간(User Space)** | **커널 공간(Ring 0)** | 커널 공간 내 디스크 관리 |
| 접근 방식 | 사용자 직접 상호작용 | **시스템 콜** 통한 간접 접근만 허용 | 쉘·프로세스의 시스템 콜 경유 접근 |
| 주요 역할 | 명령 해석·파이프 조합·스크립팅 | CPU·메모리·I/O 제어·프로세스 스케줄링 | 파일·장치·소켓 추상화·영속 저장 |

#### 한줄 요약

- 쉘은 유저 공간 인터페이스, 커널은 커널 공간 핵심 제어, 파일 시스템은 디스크 영속 관리

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쉘 인젝션(Shell Injection)**: 사용자 입력 미검증으로 악성 쉘 명령어가 삽입되어 의도치 않은 시스템 명령이 실행되는 취약점.
- **포크 폭탄(Fork Bomb)**: fork()를 재귀 호출하여 프로세스를 지수적으로 생성하여 시스템 자원을 고갈시키는 서비스 거부 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 미검증으로 **쉘 인젝션** 취약점 발생 | 입력값 특수 문자 이스케이프·허용 목록 검증 적용 | 의도치 않은 쉘 명령 실행 차단 |
| 사용자 프로그램의 직접 하드웨어 접근으로 시스템 불안정 | **User/Kernel 공간 분리** 및 특권 명령 시스템 콜 경유 강제 | 사용자 프로그램 오류로 인한 시스템 전체 영향 차단 |
| **포크 폭탄** 기반 PID·메모리 자원 고갈 | **ulimit** 기반 사용자당 최대 프로세스 수 제한 | 자원 고갈 기반 서비스 거부 방지 |

#### 한줄 요약

- 쉘 인젝션은 입력 검증으로, 직접 하드웨어 접근은 커널 공간 분리로, 포크 폭탄은 ulimit으로 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **UNIX 아키텍처 설계 기준**: 역할 분리(쉘·커널·파일 시스템)·표준 인터페이스(POSIX)·최소 권한 원칙을 유지하여 이식성과 안정성을 확보하는 설계 기준.

</details>

- 사용자 인터페이스는 **쉘**, 자원 제어는 **커널**, 데이터 보존은 **파일 시스템** 기반 역할을 분리하고 POSIX 표준 준수

#### 한줄 요약

- 쉘·커널·파일 시스템의 역할 분리와 시스템 콜 기반 접근 통제로 안정성·이식성을 확보
