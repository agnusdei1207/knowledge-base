## 미리 알고가기

- **유닉스(UNIX)**: 커널·셸·파일 시스템을 분리하고 다중 사용자를 지원하는 운영체제 계열
- **커널(Kernel)**: 특권 모드에서 프로세스·메모리·장치 자원을 관리하는 운영체제 핵심
- **셸(Shell)**: 명령을 해석해 프로세스 실행을 요청하는 사용자 프로그램
- **파일 시스템(File System)**: 파일·디렉터리의 경로·권한·저장 블록을 관리하는 운영체제 계층
- **시스템 호출(System Call)**: 사용자 프로그램이 커널 기능을 요청하는 인터페이스
- **파이프(Pipe)**: 한 프로세스 출력을 다른 프로세스 입력에 연결
- **운영체제(Operating System, OS)**: 사용자 프로그램과 하드웨어 사이에서 프로세스·메모리·장치·파일을 관리하는 시스템 소프트웨어
- **특권 모드·사용자 모드(Privileged·User Mode)**: 특권 모드는 하드웨어 제어 명령을 허용하고 사용자 모드는 응용 실행을 제한해 시스템 호출로 커널 기능을 요청하게 하는 프로세서 권한 상태
- **사용자 공간·커널 공간(User·Kernel Space)**: 사용자 공간은 셸과 응용이 격리 실행되는 주소 범위이고 커널 공간은 운영체제 핵심과 파일 시스템이 특권으로 실행되는 범위
- **스크립트·인수(Script·Argument)**: 스크립트는 여러 셸 명령을 저장한 파일이고 인수는 명령 동작에 전달하는 값
- **스크립트 주입(Script Injection)**: 신뢰하지 않은 입력이 셸 문법으로 해석되어 의도하지 않은 명령이 실행되는 취약점
- **소유자·권한 비트(Owner·Permission Bits)**: 소유자는 파일 관리 주체이고 권한 비트는 소유자·그룹·기타 사용자의 읽기·쓰기·실행 허용 여부를 기록한다.
- **허용 목록(Allowlist)**: 실행을 허용한 명령·인수만 명시하고 그 밖의 입력을 거부하는 목록
- **최소 권한(Least Privilege)**: 작업에 필요한 최소한의 사용자·파일·장치 권한만 부여하는 원칙
- **파이프 실패 전파(Pipeline Failure Propagation)**: 연결한 명령 중 하나의 실패를 전체 작업의 실패로 인식해 종료 상태로 전달하는 처리
- **메타데이터(Metadata)**: 파일 내용이 아니라 이름·크기·권한·저장 위치를 나타내는 관리 정보
- **종료 상태(Exit Status)**: 프로세스가 정상 완료 또는 오류 결과를 숫자로 반환하는 값

> **키워드:** UNIX 커널·쉘·파일시스템 3요소 (UNIX Kernel Shell)

## Ⅰ. 개요

- 정의/개념: 커널·셸·파일 시스템의 책임과 경계를 분리한 **UNIX 운영체제 구조**
- 배경/필요성: 응용의 직접 특권 접근은 **자원 충돌·권한 침해** 유발

### 쉽게 이해하기 (학습용)

- 셸이 말을 해석하고 커널이 자원을 움직이며 파일 시스템이 데이터를 보관한다.

## Ⅱ. 특징

- **커널 시스템 호출**로 프로세스·메모리·장치 통제
- **셸 명령 해석·파이프**로 단일 기능 프로그램 조합
- **파일 시스템 계층**으로 경로·권한·영속 블록 관리

### 쉽게 이해하기 (학습용)

- 작은 명령의 출입구를 파이프로 이어 복잡한 작업을 만든다.

## Ⅲ. 구조 및 구성요소

```mermaid
block
    columns 1
    U["사용자"]
    block:UNIX["UNIX 운영체제"]
        columns 1
        S["셸"]
        K["커널"]
        F["파일 시스템"]
    end
    H["하드웨어"]
    U --- S
    S --- K
    K --- F
    K --- H
    F --- H
```

| 구성요소 | 책임 |
|:---|:---|
| 셸 | **명령 해석·실행 조합** |
| 커널 | **특권 자원 통제** |
| 파일 시스템 | **경로·권한·블록 관리** |

### 쉽게 이해하기 (학습용)

- 운영체제 경계 안에서 셸은 사용자 창구, 커널은 자원 관리실, 파일 시스템은 영속 저장 서고로 배치된다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant U as 사용자
    participant S as 셸
    participant K as 커널
    participant F as 파일 시스템
    U->>S: 명령·인수
    S->>K: 1. 프로세스 실행 요청
    K->>F: 2. 실행 파일 조회
    F-->>K: 3. 파일 메타데이터
    K-->>S: 4. 종료 상태
    S-->>U: 실행 결과 출력
```

**동작 원리**

1. **프로세스 실행 요청**: 셸이 구문을 해석해 시스템 호출 구성
2. **실행 파일 조회**: 커널이 경로와 실행 권한 확인
3. **파일 메타데이터**: 실행 대상의 위치·권한 정보 제공
4. **종료 상태**: 프로세스 완료 결과를 셸의 분기 조건으로 전달

### 쉽게 이해하기 (학습용)

- 셸 창구가 명령을 시스템 호출로 바꿔 관리실에 보내고, 서고의 실행 권한과 완료표를 받아 결과를 돌려준다.

## Ⅴ. 종류 및 비교

| UNIX 구성요소 | 커널 | 셸 | 파일 시스템 |
|:---|:---|:---|:---|
| 적용 기준 | 프로세스·메모리·**장치 통제** | 명령·스크립트·**파이프 조합** | 영속 파일·**디렉터리 관리** |
| 핵심 특징 | 특권 **자원 관리** | 명령 해석·**프로세스 실행** | 경로·권한·**블록 관리** |
| 한계 | **커널 결함**의 전체 시스템 전파 | 신뢰하지 않은 입력의 **스크립트 주입** | 권한 오류·**메타데이터 손상** |

> 요약: 시스템 호출·명령·파일 연산으로 요소 경계 구분

### 쉽게 이해하기 (학습용)

- 커널은 자원, 쉘은 명령, 파일시스템은 저장을 맡는다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 신뢰하지 않은 입력을 셸 문법으로 해석해 **명령 주입** | **인수 분리·허용 목록** 적용 | 의도하지 않은 **명령 실행** 방지 |
| 셸·서비스를 과도한 권한으로 실행해 **침해 범위** 확대 | 전용 사용자와 **최소 권한** 적용 | 사용자·파일·장치의 **피해 범위** 제한 |
| 소유자·권한 비트 오류로 **민감 파일 노출** | **기본 권한 정책·변경 감사** 적용 | 무단 **읽기·변경** 방지 |
| 파이프 중간 실패를 최종 성공으로 오인해 **후속 작업 실행** | **파이프 실패 전파·종료 상태** 기록 | 자동화 작업의 **오류 조기 탐지** |

### 쉽게 이해하기 (학습용)

- 공용 열쇠로 셸을 실행하지 않고 인수 출입구와 파일 권한을 좁히며, 파이프 중간의 실패표도 끝까지 전달한다.

## Ⅶ. 결론

- **UNIX**에서 사용자 명령은 셸, 특권 자원은 커널, 영속 데이터는 **파일 시스템**으로 책임 분리

### 쉽게 이해하기 (학습용)

- 명령은 창구, 자원은 관리실, 데이터는 서고가 각각 맡는다.
