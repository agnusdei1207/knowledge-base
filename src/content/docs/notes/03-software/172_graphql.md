## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **그래프 질의 언어(Graph Query Language, GraphQL)**: 타입 스키마와 선택 필드를 사용하는 질의•실행 명세이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능을 호출하기 위한 계약이다.

</details>

- 정의/개념: 타입 스키마와 선택 필드 기반 **API 질의•실행 명세**이다.
- 배경/필요성: 고정 자원 응답으로는 화면별 조합에 **과다 응답•반복 호출이 발생한다**.

#### 한줄 요약

- 정해진 메뉴에서 화면에 필요한 항목과 하위 항목만 골라 한 요청으로 받되 서버는 주문 가능한 깊이와 양을 제한한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **타입 스키마**: 타입 스키마는 객체, 필드, 인자, 반환 타입과 널 가능성을 정의하는 GraphQL의 강한 계약이다.
- **선택 집합**: 클라이언트가 응답에서 요청한 필드 트리이다.
- **계층 리졸버**: 각 필드 값을 단계적으로 계산하는 함수 구조이다.
- **부분 오류**: 성공한 필드 데이터와 실패 경로를 함께 반환하는 방식이다.
- **점진 폐기**: 사용 중인 필드를 공지 후 단계적으로 제거하는 방식이다.

</details>

- **타입 스키마** 기반 강한 API 계약이 핵심이다.
- **선택 집합•계층 리졸버** 기반 응답 조합이 핵심이다.
- **부분 오류•점진 폐기** 기반 스키마 진화가 핵심이다.

#### 한줄 요약

- 스키마가 주문 가능한 필드와 타입을 정하고 클라이언트가 응답 모양을 고르면 리졸버가 여러 데이터 원천의 결과를 조립한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **리졸버**: GraphQL 필드의 값을 계산하는 함수이다.
- **데이터 로더**: 같은 실행 주기의 조회 키를 모아 일괄 조회하는 구성요소이다.
- **게이트웨이**: 인증과 요청 라우팅을 처리하는 진입 구성요소이다.
- **검증기**: 질의 구문•타입•깊이•비용 조건을 검사하는 구성요소이다.
- **실행 엔진**: 선택 집합의 실행 순서와 널•오류 전파 규칙을 처리하는 구성요소이다.
- **데이터 원천**: 데이터베이스•웹 API•업무 서비스에서 실제 값을 제공하는 구성요소이다.

</details>

```text
          [타입 스키마]
                 |
       [게이트웨이•검증기]
                 |
            [실행 엔진]
                 |
      [리졸버•데이터 로더]
                 |
           [데이터 원천]
```

선의 의미: 타입 계약 아래에 요청 경계, 실행 계층, 필드 해석 계층, 데이터 원천이 서로 의존하는 GraphQL의 정적 계층 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 타입 스키마 | 타입•필드•**인자•널 계약 정의** |
| 게이트웨이•검증기 | 인증•구문•**질의 비용 검증** |
| 실행 엔진 | 선택 집합•**널•오류 전파** |
| 리졸버•데이터 로더 | 필드 권한•**배치 조회•캐시** |
| 데이터 원천 | 데이터베이스•웹 API•**업무 서비스 처리** |

#### 한줄 요약

- 스키마가 메뉴, 검증기가 주문 제한, 실행 엔진이 조리 순서, 리졸버가 각 주방의 결과를 가져오는 담당자 역할을 한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **N+1 조회 문제(N Plus One Query Problem)**: 상위 목록 한 번을 조회한 뒤 각 항목의 하위 데이터를 개별 조회해 원천 호출이 급증하는 문제이다.
- **1. 질의 검증•실행 계획**: 타입•깊이•비용 조건을 검사하고 선택 집합을 구성하는 단계이다.
- **2. 필드 해석•로딩 계획**: 필드 권한과 하위 선택 순서를 결정하는 단계이다.
- **3. 키 집계•배치 조회**: 같은 실행 주기의 키를 묶어 N+1 조회를 줄이는 단계이다.

</details>

```text
GraphQL 작업•변수
        |
        v
1. 질의 검증•실행 계획
        |
        +-- 타입•비용 위반 --> 검증 오류 반환
        |
        +-- 검증 통과
                |
                v
2. 필드 해석•로딩 계획
        |
        +-- 필드 권한 거부 --> 부분 오류에 경로 기록
        |
        +-- 필드 권한 허용
                |
                v
3. 키 집계•배치 조회
                |
                v
        데이터•부분 오류 반환
```

**동작 원리**

1. **질의 검증•실행 계획**: 타입•깊이•비용 조건을 판정한다.
2. **필드 해석•로딩 계획**: 필드 권한과 하위 선택 순서를 결정한다.
3. **키 집계•배치 조회**: 같은 실행 주기의 키를 묶어 N+1을 완화한다.

#### 한줄 요약

- 상품 목록과 각 판매자를 요청하면 데이터 로더가 판매자 키를 한 번에 모아 조회해 상품 수만큼 같은 저장소를 호출하는 문제를 줄인다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **GraphQL 조합 조회**: 필요한 연관 필드를 한 요청으로 조합하는 방식이다.
- **표현 상태 전이(Representational State Transfer, REST)**: 자원을 통합 자원 식별자와 하이퍼텍스트 전송 프로토콜의 균일 인터페이스로 조작하는 아키텍처 스타일이다.

</details>

| API 방식 | GraphQL | REST |
|:---|:---|:---|
| 적용 기준 | 화면별 **연관 필드 조합** | 안정적 **자원 표현•웹 캐시** |
| 핵심 특징 | 스키마•**클라이언트 필드 선택** | URI•HTTP **균일 인터페이스** |
| 한계 | 복잡도•N+1•**필드 권한** | 과다 응답•**다중 자원 호출** |

#### 한줄 요약

- 화면마다 연관 데이터 모양이 크게 다르면 GraphQL이 호출을 줄이고 자원 단위 캐시와 단순 공개 연계가 중요하면 REST가 운영하기 쉽다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **영속 질의 허용 목록(Persisted Query Allowlist)**: 사전에 등록•승인한 질의만 실행해 임의의 고비용 질의를 제한하는 통제이다.
- **가중 복잡도 제한**: 필드•깊이•목록 크기별 비용을 합산해 질의 실행을 제한하는 통제이다.
- **인트로스펙션(Introspection)**: 실행 중인 스키마 구조를 질의로 조회하는 기능이다.
- **오류 경로**: 부분 실패가 발생한 필드 위치를 표현하는 정보이다.
- **오류 코드**: 실패 종류를 기계 판독 가능하게 표현하는 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 깊은 질의의 **처리량 폭증** | 영속 질의 허용 목록•**가중 복잡도 제한** | 연산•조회 **과부하 방지** |
| 필드별 반복의 **N+1 조회** | 요청 범위 **데이터 로더 적용** | 원천 **호출 수 감소** |
| 객체 조회 뒤 **민감 필드 노출** | 리졸버의 **객체•필드 권한 확인** | **수평 권한 우회 차단** |
| 운영 **인트로스펙션 노출** | 인트로스펙션 권한•**운영 환경 제한** | **스키마 구조 노출** 축소 |
| 부분 오류의 **실패 누락** | 오류 경로•코드•**재시도 표준화** | **필드 실패 식별** |
| 사용 중 필드의 **제거 장애** | 사용량 추적•**폐기 공지•단계 제거** | **클라이언트 호환** 유지 |

#### 한줄 요약

- 사용자가 상품 객체를 볼 권한이 있어도 원가 필드를 볼 권한은 별도일 수 있으므로 리졸버마다 필드 수준 권한을 확인해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **필드 권한**: 필드 단위로 조회 허용 여부를 판정하는 통제이다.

</details>

- **조합•비용•필드 권한**으로 GraphQL•REST을 결정한다.

#### 한줄 요약

- 선택형 응답의 호출 절감이 크고 스키마•비용•권한을 지속 관리할 수 있을 때 GraphQL을 적용해야 한다.
