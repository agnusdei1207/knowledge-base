## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **저널링(Journaling)**: 파일 시스템 변경 사항을 실제 디스크 블록(Home Block)에 쓰기 전, 전용 저널 영역에 선행 기록(WAL)하여 정전 시 빠른 복구를 보장하는 기술.
- **fsck(File System Consistency Check)**: 저널링이 없을 때 비정상 종료 후 수 TB 디스크의 모든 메타데이터를 전수 탐색하여 불일치를 검사하는 고비용 유틸리티.

</details>

- 정의/개념: 파일 시스템 변경 사항을 물리 블록에 쓰기 전 **선행 로그 기록(WAL: Write-Ahead Logging)** 에 따라 저널 영역에 트랜잭션을 커밋하는 무결성 보장 기술
- 배경/필요성: 시스템 비정상 종료(정전, 커널 패닉) 후 기존 비저널링 파일 시스템의 전수 일관성 검사(`fsck`)가 수십 TB 이상 대용량 스토리지에서 수 시간 이상의 마운트 지연과 서비스 중단을 유발하던 한계를 극복하고, 실제 블록 수정 전 전용 저널 영역에 선행 로그(WAL)를 커밋하여 **부팅 시 초고속 저널 리플레이(REDO)를 통해 수 초 내에 파일 시스템 일관성을 원자적으로 복구**할 필요

#### 한줄 요약
- WAL 기반으로 변경 로그를 선행 커밋하여 장애 시 전체 검사 없이 수 초 만에 일관성을 복구한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **WAL(Write-Ahead Logging)**: 실제 데이터/메타데이터를 원래 디스크 위치에 기록하기 전에 반드시 해당 트랜잭션 로그를 저널 영역에 먼저 기록해야 한다는 원칙.
- **체크포인트(Checkpoint)**: 저널에 커밋된 트랜잭션 블록들을 실제 Home Block으로 동기화 플러시하고 저널 공간을 비우는 작업.

</details>

- **선행 로그 기록(WAL)** 원칙 준수를 통한 파일 연산의 트랜잭션 원자성(All-or-Nothing) 확보
- 전체 디스크 검사(`fsck`) 없이 커밋된 **저널 로그 리플레이(REDO)** 만으로 수 초 내 마운트 복구
- 무결성과 성능의 절충에 따른 3대 저널링 모드(**Journal, Ordered, Writeback**) 지원

#### 한줄 요약
- 저널링은 복구 시간을 짧게 하는 대신 같은 데이터를 두 번 쓰므로, 세 가지 모드는 그 이중 기록의 범위를 얼마나 넓힐지를 정하는 눈금이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Commit Block**: 트랜잭션의 모든 Descriptor 및 데이터/메타데이터 블록이 저널에 안전하게 쓰여졌음을 증명하는 마지막 마커 블록.

</details>

```text
[파일 시스템 저널링(JBD2) 트랜잭션 구조]
|-- 파일 I/O 변경 요청 (Inode, 블록 할당 비트맵 수정)
|-- JBD2 트랜잭션 관리자 (메타데이터 변경을 원자적 트랜잭션으로 그룹화)
|-- 저널 디바이스 (Journal Device - 순환 로그 버퍼)
|   |-- Descriptor Block (트랜잭션에 포함된 블록들의 위치 정보)
|   |-- Data / Metadata Payload (실제 변경 내용 블록)
|   `-- Commit Block (트랜잭션 쓰기 완료 확정 마커)
`-- 동기화 및 복구 처리기
    |-- 정상 운용: 비동기 체크포인트 (Checkpoint -> Home Block 반영)
    `-- 장애 재부팅: 저널 리플레이 (Commit Block 확인 후 REDO 복원)
```

선의 의미: 계층 및 저널 트랜잭션 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| JBD2 트랜잭션 관리자 | 메타데이터 변경의 **원자적 그룹화** |
| 저널 영역 | Descriptor·페이로드·**Commit Block 기록** |
| 체크포인트 처리기 | 커밋 데이터를 **Home Block에 플러시** |
| 복구 관리자 | 유효 트랜잭션만 **REDO 복구** |

#### 한줄 요약
- 저널은 정본 갱신에 앞서 의도를 먼저 남기는 선행 기록 영역이므로, 복구 시 훑을 범위가 파일 시스템 전체에서 저널 구간으로 줄어든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **저널 리플레이(REDO)**: 비정상 종료 후 재부팅 시 저널의 커밋된 트랜잭션을 Home Block에 다시 순차 적용하는 복구 동작.

</details>

```text
파일 메타데이터 변경 트랜잭션 발생
        │
   저널 영역에 Descriptor Block 및 메타데이터 블록 순차 기록
        │
   저널 영역에 Commit Block 기록 및 하드웨어 플러시 (트랜잭션 확정)
        │
   정상 운용 중인가 아니면 정전/장애가 발생했는가?
   ┌────┴───────────────────────────┐
[정상 운용 상태]                 [정전/장애 후 재부팅]
백그라운드 체크포인트 수행         재부팅 시 파일 시스템 마운트
(Home Block으로 실제 기록)        저널 영역 순차 스캔
   │                                │
저널 내 트랜잭션 버퍼 해제         Commit Block이 존재하는 트랜잭션만
(공간 회수)                       Home Block에 REDO 리플레이 적용
                                   (불완전 미커밋 트랜잭션은 즉시 폐기)
```

#### 한줄 요약
- 정상 경로의 체크포인트와 장애 경로의 REDO는 같은 저널을 반대로 사용하므로, Commit Block이 찍혔는지 여부 하나가 재적용과 폐기를 가른다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Ordered Mode**: 데이터 블록을 Home Block에 먼저 쓴 후 메타데이터를 저널에 기록하여 성능과 무결성을 양립하는 리눅스 표준 모드.

</details>

| 저널링 모드 | Journal | Ordered | Writeback |
|:---|:---|:---|:---|
| 적용 기준 | 최고 데이터 무결성 | 범용 서버 균형 | 속도 우선 임시 데이터 |
| 핵심 특징 | **데이터·메타데이터 저널링** | **데이터 선기록** | **메타데이터만 저널링** |
| 한계 | 이중 쓰기 부하 | 데이터 자체 복구 제외 | 데이터 오염 가능 |

#### 한줄 요약
- 완전 무결성은 Journal 모드, 범용 표준 균형은 Ordered 모드, 극대화된 속도는 Writeback 모드를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Write Barrier(쓰기 장벽)**: 디스크 내부 휘발성 쓰기 캐시로 인해 Commit Block이 실제 데이터보다 먼저 디스크에 기록되는 순서 역전을 방지하는 하드웨어 플러시 명령.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 디스크 캐시 재정렬로 인한 **저널 Commit 순서 역전 및 무결성 파괴** | 마운트 옵션에 **Write Barrier 활성화(`barrier=1`)** | 하드웨어 쓰기 순서 강제 및 정전 시 저널 100% 신뢰성 확보 |
| Full 저널링 사용 시 **SSD 쓰기 증폭(WAF) 및 수명 단축** | 저널링 모드를 **`data=ordered`** 로 설정 | 불필요한 이중 데이터 쓰기 제거 및 SSD 수명 보호 |
| 파일 읽기 시 access time 갱신으로 인한 저널 쓰기 오버헤드 | 마운트 옵션에 **`noatime` 또는 `relatime`** 적용 | 불필요한 메타데이터 저널 쓰기 I/O 90% 제거 |
| 대규모 트랜잭션 시 저널 디바이스 병목 | 별도의 초고속 NVMe SSD를 **외장 저널 디바이스(External Journal)** 로 분리 | 메인 스토리지 I/O와 저널 로깅 완전 분리 |

#### 한줄 요약
- 저널링은 복구 시간을 쓰기 대역폭으로 사는 기법이므로, 데이터까지 저널링할지 Ordered 모드로 메타데이터만 보호할지를 유실 허용 범위로 정하고 외장 저널로 경합만 분리한다.

## Ⅶ. 결론

- 엔터프라이즈 리눅스(ext4/XFS) 및 고신뢰성 파일 시스템의 **핵심 결함 복구 및 트랜잭션 무결성 표준 기제**로 확립되었으며, 실무 운영에서는 **데이터 무결성과 성능을 절충한 `data=ordered` 모드를 기본으로, 불필요한 메타데이터 쓰기를 줄이는 `noatime`, 쓰기 순서를 강제하는 Write Barrier(`barrier=1`), 극단적 쓰기 병목 해소를 위한 독립 NVMe 외장 저널(External Journal)**을 결합하여 가용성을 보장

#### 한줄 요약
- 파일 시스템 저널링은 WAL 원칙을 통해 fsck 전수 검사의 한계를 극복하고 수 초 내 무결성을 복원하는 필수 신뢰성 기술이다.
