## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **파일 시스템 저널링(File System Journaling)**: 변경을 본래 블록보다 저널에 먼저 기록해 장애 뒤 일관성을 복구하는 방식이다.
- **저널(Journal)**: 트랜잭션 변경과 커밋 레코드를 순차 저장하는 복구 영역이다.
- **메타데이터(Metadata)**: 파일 이름•크기•블록 위치처럼 파일 구조를 설명하는 정보이다.

</details>

- 정의/개념: **파일 시스템 저널링**은 변경을 **저널**에 먼저 기록하고 커밋 단위로 복구하는 기법이다.
- 배경/필요성: 직접 갱신 중 전원 장애가 발생하면 **메타데이터**와 파일 데이터가 불일치할 수 있다.

#### 한줄 요약

- 변경 선기록과 커밋 기반 **파일 시스템 저널링**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **커밋 레코드(Commit Record)**: 트랜잭션 기록이 완료되어 복구 때 재생할 수 있음을 나타내는 표식이다.
- **원자성(Atomicity)**: 변경 묶음이 전부 반영되거나 전부 폐기되어 중간 상태가 보이지 않는 성질이다.
- **쓰기 증폭(Write Amplification)**: 한 논리 변경을 저널과 본래 블록에 거듭 기록해 실제 쓰기량이 늘어나는 현상이다.

</details>

- **커밋 레코드**로 완료된 변경만 재생해 **원자성**을 복구한다.
- **저널**의 순차 기록으로 전체 파일 시스템 검사 범위를 축소한다.
- 저널의 보호 범위가 넓을수록 **쓰기 증폭**이 증가한다.

#### 한줄 요약

- 보호 범위 확대에 따른 복구성과 **쓰기 증폭**의 절충이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **트랜잭션(Transaction)**: 함께 커밋하거나 폐기할 파일 시스템 변경 묶음이다.
- **체크포인트(Checkpoint)**: 커밋된 저널 변경을 파일 시스템의 본래 블록에 반영하는 작업이다.
- **본래 블록(Home Block)**: 저널이 아닌 파일 시스템의 최종 위치에서 데이터나 메타데이터가 저장되는 블록이다.

</details>

```text
[트랜잭션 관리자] -------- [저널 영역] -------- [체크포인트 처리기]
                                 |
                                 |
                              [복구기]
```

선의 의미: 트랜잭션 관리자와 저널 영역의 선은 변경 묶음과 커밋 기록의 보존 관계, 저널 영역과 체크포인트 처리기의 선은 커밋된 변경의 본래 블록 반영 관계, 저널 영역과 복구기의 선은 장애 복구 시 커밋 기록 참조 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 트랜잭션 관리자 | **트랜잭션** 구성과 커밋 조정 |
| 저널 영역 | 변경•커밋 기록 순차 보존 |
| 체크포인트 처리기 | **체크포인트**로 **본래 블록**에 변경 반영 |
| 복구기 | 커밋 트랜잭션 재생•미커밋 트랜잭션 무시 |

#### 한줄 요약

- **트랜잭션**, **체크포인트**, **본래 블록**의 결합이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **트랜잭션 구성**: 함께 반영할 데이터•메타데이터 변경을 하나의 복구 단위로 묶는 단계이다.
- **변경 레코드 지속화**: 갱신 내용과 대상 블록을 저널에 순차 기록하는 단계이다.
- **커밋 레코드 지속화**: 트랜잭션 전체가 복구 가능한 경계까지 저장됐음을 확정하는 단계이다.
- **체크포인트 반영**: 커밋된 변경을 파일 시스템의 본래 블록에 기록하는 단계이다.
- **커밋 트랜잭션 재생**: 재마운트 때 커밋됐지만 미반영된 변경만 다시 적용하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 파일 시스템 변경           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 트랜잭션 구성           │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 변경 레코드 지속화      │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 커밋 레코드 지속화      │
└───────┬──────────────────────┘
        ├─ 정상 진행
        │      ▼
        │ [4. 체크포인트 반영]
        │
        └─ 장애•재마운트
               ▼
          [5. 커밋 트랜잭션 재생]
               │
               ▼
         [본래 블록 일관성 복구]
```

### 동작 원리

1. **트랜잭션 구성**으로 함께 반영할 변경 묶음을 생성한다.
2. **변경 레코드 지속화**로 갱신 내용과 대상 블록을 먼저 기록한다.
3. **커밋 레코드 지속화**로 복구 가능한 완료 경계를 확정한다.
4. 정상 동작 중에는 **체크포인트 반영**으로 커밋 변경을 본래 블록에 기록한다.
5. 장애 뒤에는 **커밋 트랜잭션 재생**으로 미반영 변경을 다시 적용한다.

#### 한줄 요약

- **변경 레코드 지속화**와 장애 후 **커밋 트랜잭션 재생**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **라이트백 모드(Writeback Mode)**: 메타데이터만 저널링해 쓰기량을 줄이지만 파일 데이터의 최신성은 보장하지 않는 방식이다.
- **오더드 모드(Ordered Mode)**: 파일 데이터를 먼저 본래 위치에 기록한 뒤 메타데이터를 저널링하는 방식이다.
- **저널 모드(Journal Mode)**: 데이터와 메타데이터를 모두 저널링해 보호 범위를 넓히는 방식이다.

</details>

| 저널 모드 | Writeback | Ordered | Journal |
|:---|:---|:---|:---|
| 적용 기준 | 낮은 쓰기량이 데이터 최신성보다 우선 | 일반 파일 시스템의 비용•복구 균형 | 데이터 변경까지 원자적 복구가 필요 |
| 핵심 특징 | **라이트백 모드**는 메타데이터만 저널링 | **오더드 모드**는 데이터 선기록 후 메타데이터 저널링 | **저널 모드**는 데이터•메타데이터 모두 저널링 |
| 한계 | 파일 내용의 최신성 미보장 | 데이터•메타데이터의 시점 차이 | 쓰기 증폭•지연 증가 |

> 요약: 데이터 보호 범위로 세 저널 모드를 선택한다.

#### 한줄 요약

- 보호 범위에 따라 **라이트백 모드**, **오더드 모드**, **저널 모드**를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **쓰기 순서 장벽(Write Barrier)**: 앞선 기록의 영구 저장을 확인한 뒤 다음 기록을 허용해 커밋 순서를 지키는 제어이다.
- **강제 동기화(Filesystem Synchronization, fsync)**: 응용이 파일 변경을 저장장치까지 확정하도록 요청하는 시스템 호출이다.
- **그룹 커밋(Group Commit)**: 여러 트랜잭션을 한 번의 저장장치 동기화로 함께 확정하는 방식이다.
- **체크섬(Checksum)**: 저장 데이터에서 계산한 검증값을 비교해 저널 손상을 찾는 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 저장장치 재정렬로 커밋 순서 훼손 | **쓰기 순서 장벽**•**강제 동기화** 검증 | 커밋 원자성•내구성 유지 |
| 체크포인트 지연으로 저널 공간 고갈 | 저널 사용률•체크포인트 지연 감시 | 저널 포화에 따른 쓰기 중단 예방 |
| 데이터 저널링으로 쓰기 증폭•지연 증가 | 워크로드별 저널링 정책과 **그룹 커밋** 적용 | 보호 범위별 쓰기량•지연 절감 |
| 손상된 저널 재생으로 복구 오류 확산 | 저널 **체크섬**•복구 시험 적용 | 손상 레코드의 재생 차단 |

#### 한줄 요약

- **쓰기 순서 장벽**, **그룹 커밋**, **체크섬** 기반 운영이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **보호 범위**: 장애 복구 대상으로 메타데이터만 둘지 파일 데이터까지 포함할지를 정하는 기준이다.
- **저널링 정책 선택 기준**: 보호 범위•쓰기량•복구 시간을 비교해 라이트백•오더드•저널 모드 중 적합한 방식을 고르는 기준이다.

</details>

- **보호 범위**와 쓰기량•복구 시간을 함께 평가하는 것이 **저널링 정책 선택 기준**이다.

#### 한줄 요약

- 보호 범위•쓰기량•복구 시간에 맞는 정책 선택이 핵심이다.
