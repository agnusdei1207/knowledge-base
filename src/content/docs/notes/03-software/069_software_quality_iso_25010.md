## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISO/IEC 25010**: "좋은 소프트웨어가 대체 뭔데?"라는 질문에, "기능, 성능, 보안 등 9개 항목을 100점 맞으면 좋은 거다"라고 답을 정해놓은 국제 헌법(표준)이다.
- **제품 품질 모델(Product Quality Model)**: 소프트웨어를 뜯어볼 때, 뇌피셜로 하지 말고 딱 9가지 잣대(주특성)를 들이대서 채점하라는 프레임워크이다.
- **SQuaRE(Software Quality Requirements and Evaluation)**: 9126이니 14598이니 흩어져 있던 옛날 표준들을 "ISO 25000 시리즈"로 싹 모아서 정리한 소프트웨어 품질계의 바이블이다.

</details>

- 정의: 소프트웨어의 품질 요구사항을 정의하고 객관적으로 평가하기 위해 9대 주특성(2023년 기준)으로 체계화한 국제 제품 품질 표준 모델인 **ISO/IEC 25010**
- 배경: "잘 만들어주세요" 같은 뜬구름 잡는 소리 하다가 배포 후 **"이게 아니잖아!"라며 소송 터지는 걸 막기 위해** 팩트 기반의 잣대가 필요하기 때문

#### 한줄 요약

- 코드가 예쁜지가 아니라, 9가지 국제 표준 잣대로 '돈 주고 살 만한 품질'인지 팩트 폭행하는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제품 품질 vs 사용 품질(Product Quality vs Quality in Use)**: 제품 품질은 "버그 없고 빠름(스펙)"이고, 사용 품질은 "빠르긴 한데 유저가 쓰기엔 너무 불편해(고객 만족도)"로, 둘을 칼같이 구분해서 평가한다.

</details>

- **System & Software Product Quality Model** 9대 주특기 규정 (2023년 개정: 자율주행/AI 때문에 **Safety** 추가).
- 정성적인 뇌피셜 대신 **Quality Metrics(정량적 측정 메트릭)**로 팩트 폭행 평가 가능.
- 발주처의 입찰 제안서(RFP)부터 국가 공인 **TTA GS 인증**까지 모든 품질 시험의 절대 기준.

#### 한줄 요약

- 말장난 치지 말고 숫자로 측정(Metrics)해서 합격/불합격을 가르는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **9대 주특성(2023 개정판)**: 1. 기능 적합성, 2. 성능 효율성, 3. 호환성, 4. 상호작용 능력(사용성), 5. 신뢰성, 6. 보안성, 7. 유지보수성, 8. 유연성(이식성), **9. 안전성(Safety, 신규 추가)**.

</details>

```text
[ ISO 25010 팩트 폭행 평가 아키텍처 ]

[ 사용 맥락 (자율주행차 내비게이션) ]
           │
           ▼
    [ 9대 주특성 (신뢰성) ] ────▶ (부특성: 가용성)
                                   │
                                   ▼
    [ 합불 판정 (GS 인증) ] ◀──── [ 측정 메트릭스 (1년 다운타임 1시간 미만) ]
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **사용 맥락 (Context)** | "우주선 소프트웨어냐, 동네 쇼핑몰이냐"에 따라 품질 잣대가 달라지는 기준점 |
| **품질 주/부특성** | 9가지 대분류와 그 밑의 세부 평가 항목 (예: 보안성 $\to$ 기밀성, 무결성) |
| **품질 측정값 (Metrics)**| "속도가 빠르다" 대신 "3초 이내 렌더링"처럼 숫자로 찍어내는 팩트 지표 |
| **허용 기준 (Criteria)** | "3.1초면 불합격(Fail), 2.9초면 합격(Pass)"을 가르는 냉정한 커트라인 |

#### 한줄 요약

- 특성을 쪼개고 $\to$ 잣대를 만들고 $\to$ 숫자로 측정해서 $\to$ 커트라인을 넘는지 본다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SQuaRE Process**: 요구사항 뽑고 $\to$ 잣대 들이대고 $\to$ 시험 돌려서 $\to$ 커트라인 넘으면 인수 도장 찍어주는 팩트 폭행 흐름이다.

</details>

```text
[ 품질 평가 십자포화 흐름 ]
┌──────────────────────────────┐
│ 사업 발주서(RFP) 요구사항 접수│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 사용 맥락 및 위험도 분석  │
│ (이거 터지면 사람 죽음?)     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 품질 특성(25010) 매핑     │
│ (신뢰성과 안전성에 올인!)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 측정 지표 및 커트라인 정함│
│ (로딩 1초, 다운타임 0.1%)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 시험 수행 및 판정 (Pass/Fail)│
│ (결과 보고 도장 찍고 돈 받음)│
└──────────────────────────────┘
```

### 동작 원리

1. 사용 맥락 분석: 누가, 어디서, 터지면 어떻게 되는지 위험도 각 잼.
2. 특성 매핑: 9대 주특성 중 어디에 힘을 줄지 고름 (보안 앱이면 보안성 몰빵).
3. 측정 지표 정의: 숫자로 평가할 수 있게 메트릭과 커트라인 합의.
4. 시험 수행: 테스트베드에서 툴 돌려서 증거(로그, 응답속도) 수집.
5. 판정: 커트라인 넘었으면 합격(GS 인증 마크 획득).

#### 한줄 요약

- 말로 된 요구사항을 9대 주특성 잣대와 숫자로 바꿔서 테스트하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **2011 구판 vs 2023 신판 개정**: 12년 만에 바뀐 표준으로, AI랑 자율주행이 사람 치어 죽이는 사태를 막으려고 8개에서 9개로 늘리며 'Safety(안전성)'를 전격 추가했다.

</details>

| 개정 비교 항목 | **ISO/IEC 25010:2011 (구판)** | **ISO/IEC 25010:2023 (신판 개정 팩트)** |
|:---|:---|:---|
| 주특성 개수 | 8대 주특성 체계 | **9대 주특성 체계 (Safety 전격 추가)** |
| 안전성 (Safety) | 신뢰성 안에 꼽사리 껴있었음 | **자율주행, AI 사고 대비 '독립 주특성' 승격** |
| 사용성 (Usability)| 걍 "사용성" (Usability) | **기계와 인간의 소통 강조 "Interaction Capability"** |
| 이식성 (Portability)| 걍 "이식성" (Portability) | **클라우드 시대 맞춰 "Flexibility(유연성)"으로 업그레이드**|

#### 한줄 요약

- 옛날엔 8개였는데, 자율주행과 AI 시대가 오면서 사람 죽을까 봐 Safety(안전성)가 9번째로 추가됐다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **품질 간 상충 관계(Quality Trade-off)**: 성능(속도) 올리려고 암호화 빼면 털리고, 보안 올리려고 암호화 떡칠하면 성능이 떡락하는 개발자의 영원한 딜레마다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 성능 올리다 보안 뚫리는 **상충(Trade-off)** 발생 | "우린 보안이 우선!" 비즈니스 **가중치(Weight) 사전 합의** | 나중에 책임 전가 방지 |
| 요구사항이 "빠르게 해주세요" 식의 뇌피셜임 | **ISO 25023 정량 메트릭** 들이밀고 "1.5초 이내"로 수치화 | 빼박 팩트로만 검수 |
| 2011 구판으로 AI 자율주행차 품질 평가 불가 | **2023 개정판 Safety(안전성)** 특성 들이대고 검증 | 모빌리티/AI 인명 사고 예방 |

#### 한줄 요약

- 품질 특성끼리 부딪히면 뭐가 먼저인지 정하고, 두루뭉술한 말 대신 무조건 숫자로 평가해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ISO 25010 수용 기준(ISO 25010 Adoption Standards)**: 옛날에 계약한 건 2011년 버전으로 넘어가고, 새로 수주하는 AI 플젝은 2023년 신판으로 털어야 한다는 잣대이다.

</details>

- **ISO 25010 수용 기준** 원칙에 따라, 기존 레거시 계약은 **명시된 구판** 적용하고, 신규 모빌리티/AI는 무조건 **2023 신판(Safety 필수)** 적용 기조 확립함

#### 한줄 요약

- 발주자와 개발자가 멱살 잡고 싸우는 걸 막아주는 IT계의 솔로몬의 판결문이다.
