## 미리 알고가기

- **B-트리 (B-Tree)**: 정렬 페이지를 제자리 갱신하는 균형 트리임
- **로그 구조 병합 트리 (Log-Structured Merge-Tree, LSM-Tree)**: 메모리 쓰기를 파일로 내려 병합함
- **쓰기 전 로그 (Write-Ahead Log, WAL)**: 반영 전 변경 내용을 순서대로 기록함
- **정렬 문자열 테이블 (Sorted String Table, SSTable)**: 키순 정렬된 불변 파일임
- **블룸 필터 (Bloom Filter)**: 없는 키의 파일 탐색을 줄임
- **컴팩션 (Compaction)**: 여러 SSTable을 병합·정리함
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **99백분위 지연 (99th Percentile Latency, p99)**: 요청 99%가 완료되는 지연 기준임
- **메모리 테이블(Memtable)**: LSM-Tree가 새 쓰기를 키 순서로 모아 두는 메모리 구조임
- **불변 파일(Immutable File)**: 생성 뒤 내용을 제자리에서 수정하지 않고 새 파일과 병합하는 저장 파일임
- **임의 쓰기(Random Write)**: 연속되지 않은 여러 저장 위치를 찾아가며 기록하는 방식임
- **읽기 증폭(Read Amplification)**: 한 번의 논리 조회를 위해 여러 페이지나 파일을 추가로 읽는 비율임
- **쓰기 증폭(Write Amplification)**: 한 번의 논리 쓰기가 병합·재배치로 실제 저장장치에 여러 번 기록되는 비율임
- **공간 증폭(Space Amplification)**: 구버전과 중복 파일 때문에 논리 데이터보다 더 많은 저장 공간을 쓰는 비율임
- **쓰기 정체(Write Stall)**: 컴팩션이 쓰기 유입을 따라가지 못해 새 쓰기가 대기하거나 제한되는 현상임

## Ⅰ. 개요

- **정의/개념**: 제자리 갱신과 순차 병합 구조를 비교함
- **배경/필요성**: 읽기·쓰기 패턴 상충으로 저장 구조 선택 필요

### 쉽게 이해하기 (학습용)
- 트리는 장부를 즉시 고치고 병합 트리는 메모지에 모아 나중에 합침

## Ⅱ. 특징

- B-Tree는 점·범위 조회 경로를 로그 높이로 제한한다.
- LSM은 기록 뒤 불변 파일을 생성하고 병합한다.
- B-Tree는 임의 쓰기·페이지 분할 비용이 누적될 수 있다.
- LSM은 컴팩션과 읽기·쓰기·공간 증폭을 관리해야 한다.

### 쉽게 이해하기 (학습용)
- 즉시 정리하면 읽기 쉽고 몰아 정리하면 쓰기가 빠름

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 쓰기 경로 | 갱신 또는 파일 기록을 수행함 |
| 읽기 경로 | 트리 페이지나 여러 파일을 탐색함 |
| 유지 작업 | 페이지 분할 또는 컴팩션을 수행함 |
| 증폭 지표 | 추가 비용을 측정함 |

```text
  경로설정
      ↓
  읽기분석
      ↓
  유지작업
      ↓
  비용측정
```

> 요약: 쓰기와 읽기 및 유지 경로와 증폭 비용을 비교함

### 쉽게 이해하기 (학습용)
- 두 구조의 읽기와 쓰기 경로 및 증폭 비용을 비교함

## Ⅳ. 원리 및 절차 흐름도

```text
  쓰기수신
      ↓
  반영수행
      ↓
  구조유지
      ↓
  운영검증
```

| 절차 | 설명 |
|:---|:---|
| 쓰기수신 | 페이지나 메모리로 쓰기를 수신함 |
| 디스크반영 | 페이지 갱신이나 파일 생성을 수행함 |
| 구조유지 | 페이지 분할이나 컴팩션을 수행함 |
| 운영검증 | 읽기 지연과 증폭 비용을 측정함 |

> 요약: 페이지 갱신과 파일 병합 경로를 검증함

### 쉽게 이해하기 (학습용)
- 트리는 페이지를 고치고 병합 트리는 파일을 내려 병합함

## Ⅴ. 종류 및 비교

| 비교축 | B-Tree | LSM-Tree |
|:---|:---|:---|
| 핵심 특징 | 페이지를 찾아 제자리에서 갱신함 | 메모리 기록 후 디스크 파일로 병합함 |
| 적용 기준 | 단건과 범위 읽기 지연이 중요할 때 적용함 | 쓰기 처리량이 중요할 때 적용함 |
| 주요 위험 | 랜덤 쓰기와 페이지 분할 비용이 발생함 | 읽기와 쓰기 및 공간 증폭을 관리해야 함 |

> 요약: 읽기 지연·쓰기 증폭으로 구조 선택

### 쉽게 이해하기 (학습용)
- 읽기 지연은 트리를 우선하고 쓰기 처리량은 병합 트리를 우선함

## Ⅵ. 실무 사례

1. 로그 저장소는 컴팩션·쓰기 증폭을 확인함
2. 사용자 시스템은 트리를 적용하고 페이지 분할률을 확인함

### 쉽게 이해하기 (학습용)
- 로그 저장소는 순차 쓰기 이득뿐 아니라 컴팩션이 밀릴 때 생기는 쓰기 정체와 증폭을 함께 감시함
- 사용자 단건·범위 조회는 B-Tree의 읽기 지연과 삽입 시 페이지 분할률을 함께 측정함

## Ⅶ. 결론

- 읽기·쓰기·공간 증폭을 실측해 저장 구조 선택

### 쉽게 이해하기 (학습용)
- B-Tree와 LSM-Tree는 한쪽이 항상 빠른 구조가 아니므로 실제 읽기·쓰기 비율과 유지 작업의 꼬리 지연으로 선택해야 함
