## 미리 알고가기

- **시계열 데이터(Time-series Data)**: 타임스탬프와 측정값을 시간 순서로 기록한 데이터임
- **시계열 데이터베이스(Time-series Database, TSDB)**: 연속 표본의 시간 구간 저장·조회·집계에 최적화한 데이터베이스임
- **타임스탬프(Timestamp)**: 측정이나 사건이 발생한 시각을 나타내는 값임
- **메트릭(Metric)**: 중앙 처리 장치 사용률·요청 수처럼 반복 측정하는 항목임
- **태그(Tag)**: 서비스·인스턴스·지역처럼 시계열을 구분하고 필터링하는 차원임
- **활성 시계열 수(Active Series Count)**: 현재 수집 중인 메트릭과 태그 값 조합의 개수임
- **다운샘플링(Downsampling)**: 고해상도 원본을 분·시간 단위의 낮은 해상도 통계값으로 축약하는 처리임
- **보존 정책(Retention Policy)**: 원본과 축약본을 각각 얼마 동안 유지한 뒤 삭제할지 정하는 규칙임
- **늦게 도착한 데이터(Late-arriving Data)**: 현재 쓰기 구간보다 과거 타임스탬프를 가진 표본임
- **청크(Chunk)**: 일정 시간 범위의 표본을 함께 압축·저장하는 묶음임
- **윈도 집계(Window Aggregation)**: 지정한 시간 구간별로 합계·평균·최댓값 등을 계산하는 처리임
- **카디널리티(Cardinality)**: 메트릭과 태그 조합으로 생성될 수 있는 서로 다른 시계열 수임

## Ⅰ. 개요

- **정의/개념**: 연속 표본의 시간 구간 저장·집계를 최적화함
- **배경/필요성**: 시계열 적재량 증가로 압축·보존 정책 필요

### 쉽게 이해하기 (학습용)
- 시간 도장이 찍힌 측정값을 빠르게 쌓고 요약 및 보관하는 데이터베이스임

## Ⅱ. 특징

- 표본을 시간 파티션에 모아 청크로 압축한다.
- 시간 조건으로 최근 구간 조회와 윈도 집계를 수행한다.
- 다운샘플링·보존 정책으로 해상도와 기간을 분리한다.
- 태그 증가는 인덱스를, 늦은 표본은 재처리를 늘린다.

### 쉽게 이해하기 (학습용)
- 연속 쓰기에 강하지만 태그가 폭증하면 색인과 메모리 비용이 커짐

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 시계열 식별자 | 메트릭과 태그 집합으로 표본이 속할 시계열을 구분함 |
| 쓰기 버퍼·시간 파티션 | 표본을 구간별로 모아 순차 기록 단위를 만듦 |
| 압축 청크·시간 인덱스 | 타임스탬프와 값을 압축하고 조회할 시간 범위를 찾음 |
| 태그 인덱스 | 서비스와 인스턴스 등 조건으로 시계열 후보를 좁힘 |
| 집계·보존 계층 | 축약본을 만들고 기간이 지난 데이터를 삭제함 |

```text
  파티션할당
      ↓
  버퍼기록
      ↓
  청크압축
      ↓
  다운샘플
```

> 요약: 표본 배치·집계·보존으로 수명주기 관리

### 쉽게 이해하기 (학습용)
- 이름표와 시간 서랍 및 압축 묶음과 기간별 요약 장치로 구성됨

## Ⅳ. 원리 및 절차 흐름도

```text
  표본수신
      ↓
  계열식별
      ↓
  청크저장
      ↓
  구간집계
      ↓
  보존삭제
```

| 절차 | 설명 |
|:---|:---|
| **표본 수신** | 메트릭과 태그 및 타임스탬프와 측정값을 수신함 |
| **시계열 식별** | 메트릭과 태그 집합으로 기존 시계열을 찾거나 새 시계열을 생성함 |
| **파티션·청크 저장** | 시간 파티션에 표본을 배치하고 청크로 압축함 |
| **구간 집계** | 분과 시간 단위 통계값을 별도 시계열로 생성함 |
| **보존 정책 적용** | 유지 기간이 지난 원본과 축약 청크를 삭제함 |

> 요약: 태그·압축·집계·보존 정책 적용

### 쉽게 이해하기 (학습용)
- 표본을 구간으로 모아 압축하고 오래된 원본은 요약본만 남김

## Ⅴ. 종류 및 비교

| 판단 기준 | 시계열 데이터베이스 | 범용 관계형 데이터베이스 |
|:---|:---|:---|
| 핵심 특징 | 시간 파티션·버퍼·압축 청크로 처리함 | 행 갱신과 트랜잭션 로그로 처리함 |
| 주요 조회 | 시간 구간과 윈도 집계 | 행 조건·조인·거래 조회 |
| 수명주기 | 다운샘플링·보존 정책을 내장함 | 삭제·파티션 정책을 별도 설계함 |
| 적용 기준 | 시간 집계와 고속 연속 적재 | 관계·트랜잭션 질의 |
| 주요 위험 | 고카디널리티·늦은 표본·압축 저하 | 적재 병목·보존 작업량 증가 |

> 요약: 관계형은 행, 시계열은 시간 파티션·집계

### 쉽게 이해하기 (학습용)
- 관계형은 업무 행을 다루고 시계열은 표본과 구간 집계를 다룸

## Ⅵ. 실무 사례

1. 허용 태그를 적용하고 활성 시계열 수와 인덱스 메모리를 확인함
2. 다운샘플링을 적용하고 저장 증가량과 범위 조회 지연을 확인함

### 쉽게 이해하기 (학습용)
- 허용 태그를 제한하면 사용자 식별자 같은 고카디널리티 값이 시계열과 인덱스 메모리를 폭증시키는 일을 줄일 수 있음
- 원본은 짧게, 다운샘플은 길게 보존하면 장기 추세 조회를 유지하면서 저장 증가량을 통제할 수 있음

## Ⅶ. 결론

- 적재량·카디널리티·조회 범위·보존 비용 설계

### 쉽게 이해하기 (학습용)
- 시계열 데이터베이스는 쓰기 속도만이 아니라 태그 카디널리티·늦은 표본·다운샘플 해상도·보존 기간을 함께 관리해야 함
