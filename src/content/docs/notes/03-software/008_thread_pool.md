## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스레드 풀(Thread Pool)**: 일 들어올 때마다 일꾼(스레드)을 뽑고 자르면 돈(오버헤드)이 너무 깨지니까, 미리 정예 요원을 대기실에 박아두고 계속 부려먹는 인력 사무소이다.
- **작업 큐(Task / Work Queue)**: 일꾼들이 다 바쁠 때, 새로 들어온 일감(Task)들을 메모리에 차곡차곡 쌓아두고 대기시키는 유한/무한 컨베이어 벨트이다.
- **포화 정책(Rejected Execution Handler)**: 대기실도 일꾼도 꽉 찼을 때, "안 받아!" 하고 에러를 던지거나(Abort), 무시하거나(Discard), 호출자한테 직접 하라고 짬때리는(Caller-Runs) 무자비한 컷(Cut) 정책이다.

</details>

- 정의: 무분별한 스레드 생성/소멸 오버헤드를 막고 유한한 자원 범위 내에서 작업을 병렬로 스케줄링하고 재사용하는 **스레드 풀(Thread Pool)** 아키텍처
- 배경: 요청이 올 때마다 스레드를 새로 찍어내면, 부하가 급증할 때 **메모리 고갈**과 무자비한 문맥 전환 비용으로 서버가 터져버리기 때문

#### 한줄 요약

- 일꾼(스레드)을 매번 뽑지 않고, 큐에 일감을 쌓아서 정해진 일꾼들이 계속 재사용하며 처리하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **코어/최대 스레드 수(Core / Max Pool Size)**: 평소에 늘 밥 먹여주며 유지하는 정규직 일꾼 수(Core)와, 일감이 미친 듯이 밀려올 때 임시로 꽉꽉 채워 뽑을 수 있는 일용직 최대치(Max)이다.
- **역압력(Backpressure)**: 일감이 너무 몰려서 스레드 풀이 터지기 일보 직전일 때, 앞단(Producer)한테 "그만 쳐 보내!" 하고 멱살 잡고 속도를 늦춰버리는 흐름 제어이다.

</details>

- 스레드를 재사용해서 무식한 생성/소멸 오버헤드를 근본적으로 차단함.
- **코어/최대 스레드 수**와 한계가 있는 **작업 큐**를 세팅해서 시스템 자원을 안전하게 캡슐화함.
- 과부하가 터지면 **포화 정책(Rejected Handler)**을 발동해서 상위 시스템에 **역압력(Backpressure)**을 전파해 뻗는 걸 막음.

#### 한줄 요약

- 풀 크기와 큐 한도 설정으로 자원을 방어하고, 꽉 차면 멱살을 잡고 거절해 시스템 폭발을 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워커 스레드(Worker Thread)**: 큐 앞에서 하루 종일 `take()` 메서드를 돌리면서, 일감이 떨어지면 빛의 속도로 낚아채서 처리하고 다시 대기 타는 실무 노예이다.
- **유지 시간(Keep-Alive Time)**: 바쁠 때 임시로 뽑아놓은 일용직 스레드(Max 초과분)가 할 일 없이 이 시간 이상 놀고먹으면, 가차 없이 모가지를 날려버리는 해고 타이머이다.

</details>

```text
[ 스레드 풀 십자포화 아키텍처 ]
      [ 작업 제출자 (Client) ]
              │
              ▼
     [ 스레드 풀 실행기 ]
(수용, 거절, 워커 생성 통제관)
              │
       ┌──────┴──────┐
       ▼             ▼
 [ 유한 작업 큐 ]  [ 워커 스레드 ]
 (일감 컨베이어)    (실무 노예들)
```

| 구성요소 | 책임 |
|:---|:---|
| 스레드 풀 실행기 (Executor) | 스레드를 찍어내고, 일감을 던져주고, **유지 시간(Keep-Alive)** 넘겨서 노는 놈들 모가지를 날리는 통제관 |
| 유한 작업 큐 (Work Queue) | 워커들이 바쁠 때 들어온 일감(Runnable)들을 넘치지 않게 차곡차곡 쌓아두는 대기줄 |
| **워커 스레드** (Worker) | 큐에서 일감을 빼서 미친 듯이 연산하고, 뻗지 않게 예외 바운더리까지 방어하는 노예 |
| **포화 정책** (Rejected Handler) | 큐까지 터져나갈 때 들이밀면 에러를 뱉거나 멱살 잡고 쫓아내는 컷(Cut) 담당 일진 |

#### 한줄 요약

- 실행기가 큐에 일감을 밀어 넣으면 대기 타던 워커 스레드들이 낚아채서 처리하고, 터지면 포화 정책이 방어한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **호출자 실행 정책(CallerRunsPolicy)**: "일꾼 없으니까 일 가져온 네가 직접 해!"라며, 작업을 큐에 밀어 넣으려던 놈한테 냅다 짬때려서 시스템 유입 속도를 강제로 늦추는 최고의 역압력 방어막이다.

</details>

```text
[ 스레드 풀 십자포화 작업 수용 흐름 ]
┌───────────────────────────┐
│ 1. 새 작업 제출           │
└─────────────┬─────────────┘
              ▼
┌───────────────────────────┐
│ 2. 코어 워커 다 찼나?     │
│ (안 찼으면 워커 뽑고 실행)│
└─────────────┬─────────────┘
              ▼ (다 찼으면)
┌───────────────────────────┐
│ 3. 작업 큐 꽉 찼나?       │
│ (안 찼으면 큐에 던져둠)   │
└─────────────┬─────────────┘
              ▼ (꽉 찼으면)
┌───────────────────────────┐
│ 4. 최대 워커(Max) 찼나?   │
│ (안 찼으면 임시 워커 뽑음)│
└─────────────┬─────────────┘
              ▼ (다 찼으면 터짐)
┌───────────────────────────┐
│ 5. 포화 정책 발동         │
│ (거절, 무시, 호출자 짬처리)│
└───────────────────────────┘
```

### 동작 원리

1. 코어 검사: 지금 도는 일꾼이 **코어 수(Core)**보다 적으면 묻지도 따지지도 않고 새 일꾼을 뽑아서 일 시킴.
2. 큐 대기: 코어 일꾼이 다 바쁘면, 새 일감을 **작업 큐(Work Queue)**에 쑤셔 넣고 대기시킴.
3. 최대 워커 생성: 큐마저 꽉 찼는데 아직 **최대 수(Max)** 밑이면, 임시 일꾼을 추가로 뽑아서 불 끔.
4. 포화 정책(Reject) 발동: 최대 일꾼마저 다 차면 **포화 정책**을 터트려서 에러를 뱉거나 짬처리(CallerRuns)함.
5. 작업 및 해고: 일이 끝나면 워커는 다시 큐를 쳐다보고, 임시 워커는 할 일 없이 시간(Keep-Alive) 보내면 잘림.

#### 한줄 요약

- 코어 먼저 채우고, 큐 채우고, 맥스까지 채우다가 다 차면 멱살 잡고 거절한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **포크-조인 풀(ForkJoinPool)**: 엄청나게 큰 작업을 잘게 쪼개서(Fork) 나눠 먹고, 나중에 결과를 합치는(Join) 자바 특유의 무식하고 빠른 병렬 스레드 풀이다.

</details>

| 스레드 풀 유형 | 특징 및 매커니즘 | 주요 용도 | 장단점 |
|:---|:---|:---|:---|
| 고정 스레드 풀 (Fixed) | 정해진 수의 정규직만 유지하고, 무한/유한 큐에 다 때려 박음 | 트래픽이 뻔한 일반적인 WAS나 백엔드 서버 | 메모리만 버텨주면 안정적이지만 무한 큐면 지연 터짐 |
| 캐시 스레드 풀 (Cached) | 일 들어오면 무한대로 임시직 찍어내고 놀면 자름 | 엄청 짧게 끝나는 가벼운 비동기 작업 떡칠할 때 | 대기는 없지만 부하 터지면 스레드 수만 개 찍고 서버 뒤짐 |
| 스케줄 스레드 풀 (Scheduled) | 정해진 시간이나 주기마다 꼬박꼬박 일꾼을 깨워서 시킴 | 매일 도는 배치 작업이나 1분마다 도는 헬스체크 | 시간이나 주기를 맞추는 데 최적화됨 |
| **포크-조인 풀** (ForkJoin) | 워커끼리 일감 없으면 남의 큐에서 훔쳐 옴 | 1억 개 배열 정렬처럼 잘게 쪼갤 수 있는 CPU 빡센 연산 | 부하 균형은 쩔지만 I/O 블로킹 터지면 노답됨 |

#### 한줄 요약

- 일반 서버는 고정 풀을 쓰고, 시간 맞출 땐 스케줄 풀, CPU를 극한으로 쪼갤 땐 포크-조인 풀을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **작업 훔치기(Work-Stealing)**: 자기 큐에 있는 일감을 다 끝내고 놀고 있는 워커가, 딴 워커의 큐 꼬리(Tail)에서 몰래 일감을 훔쳐 와서 병렬로 돌려버리는 극강의 효율 꼼수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 큐를 무한으로 뚫어놨다가 일감 100만 개 쌓이고 메모리(OOM) 터져서 죽음 | 큐 크기에 리밋을 거는 **유한 작업 큐**와 타임아웃을 강제로 박아버림 | 일감이 무식하게 쌓이는 걸 막고 메모리 한계선(Limit) 완벽 방어 |
| 풀 꽉 찼다고 에러(Abort) 뱉으면서 중요한 트랜잭션 데이터가 줄줄 새서 날아감 | 거절 정책을 **호출자 실행(CallerRunsPolicy)**으로 바꿔서 짬처리 시킴 | 넘치는 트래픽을 거부하지 않고 늦춰버리는 자연스러운 **역압력(Backpressure)** 전파 |
| CPU 작업이랑 디스크(I/O) 읽는 작업을 한 풀에 섞었다가 스레드 싹 다 블로킹됨 | CPU 바운드 풀(코어 수 비례)과 I/O 바운드 풀을 아예 **분리해서 찢어버림** | I/O 병목 때문에 소중한 CPU 코어가 멍때리고 노는 대형 참사 원천 차단 |

#### 한줄 요약

- 큐 무한대는 독이므로 유한 큐를 쓰고, 거절은 짬처리로 막으며, CPU와 I/O 풀은 반드시 찢어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스레드 풀 용량 산정 공식(Thread Pool Sizing Formula)**: CPU 작업은 "코어 수 + 1"로 타이트하게 잡고, I/O 작업은 대기 시간 비례해서 왕창 늘려버리는 국룰 튜닝 계산법이다.

</details>

- **스레드 풀 용량 산정 공식** 원칙에 따라, CPU 작업은 빡세게 통제하고, I/O 작업은 **별도 유한 풀과 큐**를 파서 격리하는 채택 기조 확립함

#### 한줄 요약

- CPU 몫은 코어 수에 맞추고, I/O 작업은 분리된 스레드 풀을 만들어 블로킹을 격리해야 한다.
