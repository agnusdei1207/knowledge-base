## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서버리스 컴퓨팅 & FaaS(Function as a Service)**: 서버 프로비저닝 없이 이벤트 트리거에 응답하여 무상태 함수를 실행하고 ms 단위 실행 시간만큼만 과금하는 모델.
- **MicroVM(Firecracker)**: AWS Lambda가 사용하는 수 밀리초 단위 초고속 부팅 및 완전 커널 격리를 제공하는 오픈소스 가상화 기술.

</details>

- 정의/개념: 서버 인프라 관리 없이 이벤트 트리거 시 무상태(Stateless) 함수 코드를 자동 확장 실행하고 실제 실행 시간(ms)만큼만 과금하는 컴퓨팅 패러다임
- 배경/필요성: 상시 구동 서버 아키텍처에서 간헐적 트래픽 수용을 위해 고용량 인프라를 상시 유지함에 따른 막대한 유휴 자원 비용 낭비 및 OS 패치/용량 산정 오버헤드 한계

#### 한줄 요약
- 이벤트 기반 무상태 실행과 초정밀 종량 과금을 통해 인프라 운영 오버헤드를 제로화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Cold Start**: 유휴 상태의 함수 인스턴스를 최초로 초기화하고 런타임을 구동할 때 발생하는 수 초의 초기 지연.
- **Pay-per-Execution**: 대기 시간 비용 0원으로, 실제 함수가 호출되어 동작한 1ms 단위 시간과 메모리 할당량에만 비례 과금.

</details>

- 서버 프로비저닝, OS 패치, 용량 산정이 완전히 불필요한 Zero Server Management
- 이벤트 유입량에 따라 0개에서 수천 개로 즉각 확장되는 자동 스케일아웃(Auto-Scaling)
- 함수 호출 횟수와 실행 시간(ms)에만 비례하여 청구되는 초정밀 종량 과금 체계

#### 한줄 요약
- 서버 소유와 상태 보유를 포기한 대가로 유휴 비용과 운영 부담을 없앤 모델이므로, 장기 연결이나 인메모리 상태가 필요한 워크로드에는 그대로 적용되지 않는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **FaaS 4대 구성 계층**: Event Sources(트리거 신호), Control Plane(동시성/인증 통제), Function Runtime(MicroVM 격리 실행), External State(외부 영속 DB).

</details>

```text
[서버리스 FaaS 구성]
|-- 이벤트 소스
|-- FaaS 제어면
|-- 함수 런타임
`-- 외부 영속 저장소
```

선의 의미: 계층 및 이벤트 소스가 FaaS 제어면을 트리거하여 무상태 함수 컨테이너를 가동하고 외부 DB에 결과를 기록하는 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 이벤트 소스 (Event) | HTTP, S3 객체 생성, 큐 메시지 등 함수 실행을 유발하는 트리거 신호 제공 | 비동기/동기 트리거 |
| FaaS 제어면 (Control) | 인증/인가, 동시성 한도 검사, 컨테이너 웜/콜드 상태 판별 및 스케줄링 총괄 | 초고속 라우팅 |
| 함수 런타임 (Runtime) | Firecracker MicroVM 기반으로 격리된 환경에서 사용자 코드를 초고속 실행 | 5ms 부팅 격리 |
| 외부 영속 저장소 (State) | 무상태 함수의 한계를 극복하기 위해 결과 데이터 및 세션 상태를 외부 보존 | DynamoDB, S3 |

#### 한줄 요약
- 상태를 함수가 아닌 외부 저장소가 떠맡기 때문에 제어면이 인스턴스를 언제 만들고 버리든 데이터 정합성이 유지되며, 그 덕분에 런타임을 자유롭게 회수할 수 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **FaaS 실행 5단계**: 이벤트 도착 $\to$ 권한 검증 $\to$ 웜/콜드 환경 준비 $\to$ 함수 로직 실행 $\to$ 결과 반환 및 자원 회수.

</details>

```text
S3 버킷에 신규 이미지 업로드 이벤트 발생
        │
   [이벤트 신호 도착] S3가 EventBridge를 통해 Lambda FaaS 제어면으로 알림 전송
        │
   [권한 및 쿼터 검증] Lambda 실행 역할(IAM Role)과 계정별 동시성(Concurrency) 한도 확인
        │
   [런타임 환경 준비] Warm 컨테이너를 우선 탐색하고, 부재 시 신규 MicroVM 즉각 기동(Cold Start)
        │
   [함수 로직 실행] 이미지 리사이징 핸들러 함수가 밀리초 단위로 초고속 연산 수행
        │
   가공 결과를 S3에 저장하고 클라이언트에 200 OK 회신 후 런타임은 대기/회수
```

#### 한줄 요약
- 웜 컨테이너 재사용 여부가 응답 지연의 자릿수를 가르며, 실행 후 런타임을 회수하는 정책이 곧 유휴 비용 절감의 근거이자 콜드 스타트의 원인이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **상시 서버(EC2) vs 서버리스 FaaS**: 24/365 고정 과금 및 수동 관리(EC2)와 이벤트 트리거 기반 자동 확장 및 종량 과금(FaaS).

</details>

| 비교 항목 | 상시 서버 가상머신 (EC2 / VM) | 서버리스 FaaS (AWS Lambda) |
|:---|:---|:---|
| 인프라 관리 범위 | OS 패치, 용량 산정, 네트워크 직접 관리 | 인프라 관리 0% (비즈니스 코드만 작성) |
| 과금 및 비용 모델 | 24/365 가동 시간 기준 고정 렌탈 과금 | 함수 실행 시간(1ms 단위) 및 호출 수 종량 과금|
| 확장 탄력성 | 수 분(Minutes) 소요 (오토스케일링 지연) | 밀리초(Milliseconds) 단위 즉각 스케일아웃 |
| 최적 적용 워크로드| 24시간 지속 연결, 15분 이상 장기 배치 | 이벤트 구동 처리, 비정기 배치, 경량 API |

#### 한줄 요약
- 항시 가동과 지속 연결은 EC2/컨테이너, 이벤트 구동 및 간헐적 처리는 서버리스 FaaS를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Provisioned Concurrency**: 콜드 스타트를 원천 제거하기 위해 N개의 함수 인스턴스를 미리 초기화하여 항상 대기시키는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 자바/스프링 함수 최초 기동 시 수 초의 콜드 스타트 지연 | AWS Lambda SnapStart 또는 Provisioned Concurrency 사전 적용 | 초기 응답 시간 수십 ms 이내로 단축 |
| 수천 개 함수 동시 실행 시 백엔드 RDBMS 연결 풀 고갈 | RDS Proxy 도입으로 데이터베이스 커넥션 풀링 및 다중화 | DB 연결 초과 장애 완벽 방지 |
| 대용량 데이터 처리 중 단일 함수 최대 실행 시간(15분) 초과 | AWS Step Functions 도입으로 워크플로우를 단계별 분할 제어 | 장기 실행 프로세스 무중단 완결 |
| 함수 로직 에러 시 이벤트 유실 위험 | DLQ(Dead Letter Queue) 연동 및 SQS 실패 메시지 재처리 구축 | 데이터 무손실 100% 보장 |

#### 한줄 요약
- 콜드 스타트와 커넥션 고갈, 15분 실행 제한은 인스턴스를 소유하지 않아 얻은 종량 과금의 이면이며, 사전 웜업과 프록시 도입은 그 비용을 일부 되사는 선택이다.

## Ⅶ. 결론

- 이벤트 기반 아키텍처(EDA) 및 클라우드 네이티브 비즈니스 로직 고속 출시를 위한 가장 진보된 서버리스 컴퓨팅 패러다임으로 정립되었으며, 실무 구축 시에는 초기 응답 지연을 제거하는 Lambda SnapStart/Provisioned Concurrency 적용, 대규모 동시 실행 시 RDBMS 커넥션 고갈을 방어하는 RDS Proxy 연동, 15분 실행 한계를 극복하는 Step Functions 오케스트레이션 및 이벤트 유실을 방어하는 SQS DLQ(Dead Letter Queue)를 결합하여 개발 생산성과 운영 안정성을 완벽히 조화

#### 한줄 요약
- 서버리스 FaaS는 인프라 관리 제로화와 이벤트 구동 초정밀 종량 과금을 통해 비즈니스 민첩성을 극대화하는 클라우드 네이티브의 핵심 컴퓨팅 모델이다.
