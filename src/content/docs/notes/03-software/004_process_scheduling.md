## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로세스 스케줄링(Process Scheduling)**: CPU라는 한정된 자원을 대기줄(Ready Queue)에 있는 수많은 프로세스들에게 누구부터 얼마나 줄지 공정하고 깐깐하게 따지는 커널의 배급 정책이다.
- **선점형/비선점형 스케줄링(Preemptive vs Non-Preemptive)**: 일하고 있는 놈의 멱살을 잡고 강제로 쫓아낼 수 있으면 선점형, 자기가 알아서 나갈 때까지 손가락 빨고 기다려야 하면 비선점형이다.
- **완전 공정 스케줄러(Completely Fair Scheduler, CFS)**: 리눅스 커널이 쓰는 방식으로, 레드-블랙 트리를 써서 CPU를 덜 쓴 불쌍한 놈부터 무조건 먼저 챙겨주는 평등주의 배급 기법이다.

</details>

- 정의: 시스템 응답시간과 처리량을 극대화하기 위해, 커널이 대기 중인 프로세스들에게 CPU 자원을 선점/비선점 방식으로 배분하는 **프로세스 스케줄링 알고리즘**
- 배경: 멍청하게 도착한 순서대로만(FCFS) 처리하면, 1초면 끝날 짧은 작업이 10시간짜리 작업 뒤에 묶여서 하루 종일 대기하는 재앙이 터지기 때문

#### 한줄 요약

- CPU 자원을 덜 기다리고, 덜 굶으면서, 공평하게 나눠 쓰게 만드는 교통정리 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **타임 슬라이스(Time Quantum / Time Slice)**: 선점형 환경에서 "너 딱 10밀리초만 쓰고 나와!" 하고 한 프로세스에게 허락해 주는 제한 시간이다.
- **호위 효과(Convoy Effect)**: CPU를 무식하게 오래 쓰는 덩치 큰 프로세스 하나 때문에, 뒤에 서 있는 짧고 날랜 프로세스들이 줄줄이 갇혀서 굼벵이가 되는 최악의 병목 현상이다.
- **기아 현상(Starvation)**: 우선순위가 낮거나 CPU를 길게 쓴다는 이유로, 스케줄러한테 영원히 무시당해서 영양실조(실행 불가)로 굶어 죽는 현상이다.

</details>

- 멱살 잡고 쫓아내는 **선점형**(RR, MLFQ, CFS)과 자발적으로 나갈 때까지 냅두는 **비선점형**(FCFS, SJF)으로 배급 정책이 찢어짐.
- **타임 슬라이스**를 너무 짧게 주면 문맥 전환 딜레이로 터지고, 길게 주면 응답성이 쓰레기가 되는 지독한 상충 관계가 존재함.
- 계속 무시당해서 굶어 죽는 **기아 현상**을 막기 위해, 오래 대기하면 우선순위를 올려주는 에이징(Aging) 처방이 필수적임.

#### 한줄 요약

- 선점형은 빠릿하지만 오버헤드가 크고, 비선점형은 오버헤드는 작지만 호위 효과(병목)로 터진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 실행 시간(Virtual Runtime, vruntime)**: CFS가 프로세스들의 실제 실행 시간에 우선순위 가중치를 곱해서, 누가 진짜로 CPU를 덜 썼는지 깐깐하게 계산해 낸 억울함의 지표이다.
- **레드-블랙 트리(Red-Black Tree)**: CFS가 수많은 프로세스들을 vruntime(억울함) 순서대로 쫙 세워놓고, 제일 불쌍한 놈(왼쪽 끝)을 빛의 속도로 뽑아 쓰기 위해 만든 자가 균형 나무 구조이다.

</details>

```text
[ 프로세스 스케줄링 십자포화 디스패치 파이프라인 ]
  [ 준비 큐 (레드-블랙 트리/FIFO) ]
                 │ (대기 명단)
                 ▼
         [ OS 커널 스케줄러 ]
                 │ (다음 타자 선택)
                 ▼
          [ 디스패처 (교대꾼) ] ── (타이머 인터럽트)
                 │
                 ▼
           [ CPU (실행 코어) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **준비 큐** (Ready Queue) | FCFS(그냥 큐)나 CFS(**레드-블랙 트리**) 등 알고리즘 입맛에 맞게 프로세스 장부(PCB)를 꽂아둔 창고 |
| OS 스케줄러 | 우선순위나 **vruntime**을 매의 눈으로 계산해서 다음 CPU 권력을 쥘 타자를 확정하는 통제관 |
| 디스패처 (Dispatcher) | 스케줄러가 지목한 타자의 뇌(Context)를 복원하고 유저 모드로 전환해서 CPU에 꽂아주는 실무자 |
| 하드웨어 타이머 | 프로세스가 **타임 슬라이스**를 다 쓰면 무자비하게 알람(인터럽트)을 터트려 쫓아내는 시계 |

#### 한줄 요약

- 스케줄러가 준비 큐에서 제일 급한 놈을 고르면 디스패처가 꽂고, 타이머가 시간 다 되면 쫓아낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **에이징(Aging)**: 우선순위가 낮아서 CPU를 못 잡고 굶어 죽어가는 놈들의 나이(대기 시간)를 먹여서, 강제로 등급을 팍팍 올려주는 구제역 기법이다.

</details>

```text
[ 스케줄링 반복 타이머 십자포화 흐름 ]
┌───────────────────────────┐
│ 1. 준비 큐 갱신 (에이징)  │
│            │              │
│            ▼              │
│ 2. 다음 타자 선택         │
│            │              │
│            ▼              │
│ 3. 뇌 복원 및 디스패치    │
│            │              │
│            ▼              │
│   [ CPU 실행 및 연산 ]    │
│      ┌─────┴──────┐       │
│ (스스로 방 뺌)   (알람 터짐) │
│      ▼            ▼       │
│ [ I/O 대기 ]  4. 강제 선점│
│                   │       │
│                   ▼       │
│            5. 뇌 보존     │
│                   └─── (반복)
└───────────────────────────┘
```

### 동작 원리

1. 준비 큐 갱신: 대기 중인 프로세스들이 굶어 죽지 않게 **에이징(Aging)**을 먹여서 우선순위를 갱신함.
2. 다음 타자 선택: 알고리즘(최소 **vruntime** 등)을 돌려서 지금 가장 CPU가 시급한 놈을 콕 집어냄.
3. 뇌 복원 및 디스패치: 뽑힌 놈의 뇌(문맥)를 복원하고 **타임 슬라이스**를 쥐여서 CPU에 냅다 던짐.
4. 강제 선점: 제한 시간이 끝나면 타이머 인터럽트가 폭발하면서 멱살을 잡고 CPU 권력을 회수함.
5. 뇌 보존: 하던 일(문맥)을 보존하고 다시 준비 큐로 내쫓은 뒤, 1번부터 뺑뺑이를 돎.

#### 한줄 요약

- 에이징으로 갱신하고 타자를 골라 실행시키다, 시간 다 되면 멱살 잡고 끌어내서 저장하는 뺑뺑이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다단계 피드백 큐(Multi-Level Feedback Queue, MLFQ)**: 준비 큐를 여러 계급으로 쪼개놓고, 시간 안에 일을 못 끝내면 밑바닥으로 강등시키고, I/O 터져서 쫓겨나면 계급을 유지해 주는 악랄하면서도 똑똑한 스케줄러이다.

</details>

| 스케줄링 알고리즘 | 선점 유무 | 핵심 매커니즘 | 주요 장단점 |
|:---|:---|:---|:---|
| **FCFS** (First-Come First-Served) | 비선점 | 줄 선 순서대로 끝날 때까지 다 쓰게 해줌 | 구현은 쉽지만, 긴 놈 하나 때문에 다 막히는 **호위 효과** 폭발 |
| **SJF** (Shortest Job First) | 혼합 | 실행 시간이 제일 짧을 것 같은 놈부터 새치기 시켜줌 | 대기시간은 최소지만, 긴 놈은 영원히 못 실행되는 **기아 현상** 발생 |
| **RR** (Round Robin) | 선점형 | 정해진 **타임 슬라이스**만큼 찔끔찔끔 돌려쓰며 빙글빙글 돎 | 공평하고 응답성은 높지만, 문맥 전환 오버헤드로 시간 다 버림 |
| **MLFQ** | 선점형 | 여러 계급의 큐를 두고 일 못 끝내면 강등, 잘하면 승격시킴 | I/O 바운드랑 CPU 바운드를 기가 막히게 적응해서 쳐냄 |
| **CFS** | 선점형 | **vruntime**을 따져서 시간 덜 쓴 놈부터 배분함 | 무자비한 완전 공정성을 씹어먹지만 트리 가중치 계산이 귀찮음 |

#### 한줄 요약

- 무식하게 줄 세우면 FCFS, 빙글빙글 돌리면 RR, 계급 갈라치면 MLFQ, 완전 공평은 CFS다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **나이스(Nice Value)**: 리눅스에서 "내가 얼마나 양보심이 넘치는지(-20부터 19까지)" 나타내는 수치로, 높을수록 CPU를 덜 먹고 착해져서 다른 놈한테 자원을 퍼준다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SJF나 MLFQ에서 무거운 CPU 작업들이 차례를 못 받고 굶어 죽는 **기아 현상** 터짐 | 주기적으로 밑바닥에 깔린 놈들의 계급을 팍팍 올려주는 **에이징(Aging)** 강제 투여 | 영양실조로 프로세스가 죽어버리는 재앙을 원천 차단 |
| 라운드 로빈(RR)에서 할당 시간을 너무 짧게 줘서 CPU가 교대만 하느라 뻗어버림 | 시스템 응답 목표를 따져서 **타임 슬라이스** 크기를 절묘하게 튜닝함 | 미친 듯한 문맥 전환 오버헤드를 줄이고 실제 일하는 시간(가용률) 사수 |
| 한 프로세스가 CPU를 100% 독식해서 나머지 시스템 전체가 렉에 걸려 멈춤 | **나이스(Nice) 값**을 조작해서 양보심을 늘리고 CPU 몫을 강제로 후려침 | 특정 프로세스의 미친 독주를 막고 시스템 전반의 응답성 회복 |

#### 한줄 요약

- 굶어 죽기 전에 에이징으로 살리고, 교대병 걸리면 타임 슬라이스를 늘리며 독식은 나이스 값으로 패라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스케줄링 알고리즘 선택 기준(Process Scheduling Selection Criteria)**: 이 시스템이 사용자랑 상호작용을 빡세게 하는지, 아니면 뒤에서 조용히 묵직한 연산만 돌리는지에 따라 배급 방식을 정하는 잣대이다.

</details>

- **스케줄링 알고리즘 선택 기준** 원칙에 따라, 어지간한 범용 OS는 닥치고 **CFS**나 **MLFQ**, 1밀리초도 늦으면 안 되는 특수 제어 시스템은 **실시간(RTOS) 스케줄러** 채택 기조 확립함

#### 한줄 요약

- 사용자와 대화하는 서버는 CFS나 MLFQ를 쓰고, 핵폭탄 날아오는 걸 막는 제어기에는 실시간 OS를 써라.
