## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CPU 스케줄링(Process Scheduling)**: 준비 큐에 대기 중인 프로세스들 중 CPU를 할당할 대상을 결정하는 운영체제 커널의 핵심 알고리즘.
- **선점/비선점(Preemption/Non-preemption)**: 강제로 CPU를 회수할 수 있는 선점형과 스스로 CPU를 반납할 때까지 기다리는 비선점형 방식.

</details>

- 정의/개념: 다중 프로그래밍 환경에서 **선점/비선점 정책 및 타임 퀀텀**을 기반으로 CPU 점유 순서를 결정하는 **프로세스 스케줄링** 기법
- 배경/필요성: 긴 작업의 CPU 독점으로 인한 **호위 효과(Convoy Effect) 및 기아 현상(Starvation) 해결 불가**

#### 한줄 요약
- 응답성과 공정성을 위해 준비 큐의 프로세스들에게 CPU 자원을 최적 분배한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **호위 효과(Convoy Effect)**: CPU 버스트가 긴 프로세스 뒤에 짧은 작업들이 밀려 시스템 전체 평균 대기시간이 급증하는 현상.
- **기아 현상(Starvation)**: 우선순위가 낮은 프로세스가 고우선순위 작업에 밀려 무한정 CPU를 할당받지 못하는 상태.

</details>

- **선점형**(RR, MLFQ, CFS)과 **비선점형**(FCFS, SJF) 스케줄링 방식 구분
- **타임 슬라이스(Time Quantum)** 크기 설정에 따른 문맥 전환 오버헤드와 응답시간 간 트레이드오프
- 장기 대기 프로세스의 **기아 현상** 방지를 위한 에이징(Aging) 메커니즘 필수

#### 한줄 요약
- 선점형은 응답성이 우수하고, 비선점형은 오버헤드가 적으나 호위 효과가 발생할 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **vruntime(가상 실행 시간)**: 리눅스 CFS에서 프로세스의 실제 실행 시간에 우선순위 가중치를 반영하여 산출하는 공정 배분 척도.
- **레드-블랙 트리(Red-Black Tree)**: CFS 스케줄러가 $O(\log n)$ 시간에 최소 vruntime 프로세스를 탐색하기 위해 사용하는 자가 균형 이진 탐색 트리.

</details>

```text
[운영체제 CPU 스케줄러 구조]
|-- 준비 큐 (Ready Queue)
|   |-- FCFS / SJF : FIFO 및 버스트 시간 정렬 큐
|   |-- Round-Robin : 원형 순환 큐 (Circular Queue)
|   |-- MLFQ : 다단계 우선순위 피드백 큐
|   `-- CFS : vruntime 기반 레드-블랙 트리 (Red-Black Tree)
|-- 커널 스케줄러 (우선순위 및 vruntime 계산 정책 적용)
|-- 디스패처 (Dispatcher - PCB 문맥 복원 및 CPU 이양)
`-- 하드웨어 타이머 (타임 슬라이스 만료 시 선점 인터럽트 트리거)
```

선의 의미: 계층 및 스케줄링 자료구조

| 구성요소 | 책임 |
|:---|:---|
| 준비 큐(Ready Queue) | 알고리즘에 따른 자료구조(FIFO, 다단계 큐, **레드-블랙 트리**)로 PCB 보관 |
| 커널 스케줄러 | 스케줄링 정책에 따라 차기 실행 프로세스를 결정하고 큐 재정렬 |
| 디스패처(Dispatcher) | 선정된 프로세스의 레지스터를 복원하고 유저 모드로 전환하여 **CPU 이양** |
| 하드웨어 타이머 | **타임 슬라이스** 만료 시 타이머 인터럽트를 발생시켜 강제 선점 유도 |

#### 한줄 요약
- 준비 큐 자료구조, 커널 스케줄러 정책, 디스패처, 하드웨어 타이머가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **에이징(Aging)**: 대기 시간이 길어질수록 프로세스의 우선순위를 점진적으로 높여 기아를 방지하는 기법.

</details>

```text
준비 큐에서 대기 중인 프로세스들에 에이징(Aging) 적용
        │
   스케줄러가 알고리즘 정책(최소 vruntime / 최단 작업 등)으로 프로세스 선정
        │
   디스패처가 문맥을 복원하고 타임 슬라이스를 부여하여 CPU 이양
        │
   명령어 실행 중
   ┌────┴───────────────────────────┐
타임 슬라이스 만료  I/O 요청 또는 자발 반납  실행 완료 (exit)
   │                  │                  │
타이머 선점 발생    대기 큐로 전이      프로세스 종료
(문맥 저장 후      (Blocked)          (자원 해제)
준비 큐 복귀)
```

#### 한줄 요약
- 에이징 적용 → 스케줄러 프로세스 선정 → 디스패치 실행 → 타임아웃 선점 또는 I/O 대기 순으로 순환한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MLFQ**: CPU 버스트가 길면 하위 큐로 강등하고 I/O 바운드는 상위 큐로 유지하는 적응형 스케줄러.
- **CFS(Completely Fair Scheduler)**: vruntime이 가장 작은 프로세스를 우선 선택하는 리눅스 표준 완전 공정 스케줄러.

</details>

| 스케줄링 알고리즘 | FCFS (선입선출) | SJF / SRTF (최단작업) | RR (라운드로빈) | MLFQ (다단계피드백) | CFS (완전공정) |
|:---|:---|:---|:---|:---|:---|
| 선점 여부 | 비선점형 | 비선점(SJF) / 선점(SRTF) | **선점형** (타임 퀀텀) | **선점형** (우선순위 강등) | **선점형** (vruntime) |
| 핵심 메커니즘 | 도착 순서대로 실행 | 실행 시간 최단 우선 | 타임 슬라이스 순환 | 큐 간 이동 및 에이징 | 레드-블랙 트리 탐색 |
| 한계점 | **호위 효과** 극심 | **기아 현상**, 버스트 예측 불가 | 잦은 문맥 전환 지연 | 튜닝 복잡도 높음 | 나이스 값 가중치 의존 |
| 주요 응용처 | 일괄 처리 배치 시스템 | 작업 시간 확정 배치 잡 | 시분할 대화형 시스템 | 일반 시분할 운영체제 | 현대 범용 Linux OS |

#### 한줄 요약
- 대화형 공정성은 CFS/MLFQ, 단순 배치는 FCFS, 이론상 최단 대기시간은 SJF를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Nice Value(나이스 값)**: 리눅스에서 프로세스의 우선순위 가중치를 -20(최고)부터 19(최저)까지 조정하는 설정값.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 우선순위 스케줄링에서 저우선순위 프로세스 **기아 현상** | 대기 시간 비례 **에이징(Aging)** 적용 | 저우선순위 프로세스의 무한 대기 원천 방지 |
| 너무 짧은 타임 슬라이스로 인한 문맥 전환 오버헤드 | 시스템 응답성과 처리량을 고려한 타임 퀀텀 튜닝(10~100ms) | 문맥 전환 지연 축소 및 CPU 순수 연산 가용률 극대화 |
| 특정 CPU 집약 프로세스의 코어 독점으로 응답성 저하 | **Nice 값(-20~19)** 조정 및 CFS cgroups CPU 쿼터 설정 | 프로세스 간 공정 배분 및 서비스 레이턴시 보호 |
| 실시간 프로세스와 일반 프로세스 혼재 시 마감시간 위반 | 실시간 스케줄링 정책(SCHED_FIFO / SCHED_RR) 격리 적용 | 하드/소프트 실시간 작업의 결정론적 우선순위 보장 |

#### 한줄 요약
- 에이징 기법, 타임 퀀텀 최적화, Nice 값 통제, 실시간 정책 분리로 스케줄링 효율을 극대화한다.

## Ⅶ. 결론

- 범용 서버는 **CFS/MLFQ**, 실시간 처리는 **SCHED_FIFO** 선택

#### 한줄 요약
- 워크로드의 특성(I/O 바운드 vs CPU 바운드)과 실시간성 요구에 따라 최적의 스케줄링 정책을 선택해야 한다.
