## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **선점/비선점 및 타임 슬라이스(Preemption & Time Quantum)**: 프로세스의 자발적 반환을 기다리지 않고 타이머 인터럽트로 강제 선점하여 시분할 공정성을 부여하는 제어 방식.
- **호위 효과 및 기아(Convoy Effect & Starvation)**: CPU 버스트가 긴 프로세스 뒤에 짧은 작업들이 밀려 평균 대기시간이 폭증하거나 저우선순위 작업이 무한 대기하는 문제.

</details>

- 정의/개념: 다중 프로그래밍 환경에서 **선점/비선점 정책 및 타임 슬라이스(Quantum)** 를 기반으로 CPU 코어 점유 순서를 결정하는 OS 자원 관리 기법
- 배경/필요성: 긴 작업의 CPU 독점에 따른 호위 효과(Convoy Effect) 방지 및 시스템 응답성과 공정성 보장 필요

#### 한줄 요약

- CPU 이용 효율과 응답성을 최적화하기 위해 대기 중 프로세스에게 할당 방식·우선순위·시간 슬라이스로 CPU를 배분하는 기법

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **타임 슬라이스(Time Quantum)**: 선점형 스케줄링에서 한 프로세스에게 허용하는 최대 CPU 연속 실행 시간.
- **호위 효과(Convoy Effect)**: CPU 집약적인 장기 프로세스 뒤에 단기 프로세스들이 대기하면서 전체 평균 대기시간이 증가하는 현상.
- **기아 현상(Starvation)**: 우선순위가 낮은 프로세스가 높은 우선순위 프로세스에게 계속 밀려 CPU를 할당받지 못하는 상태.

</details>

- **선점형**(RR·MLFQ·CFS)과 **비선점형**(FCFS·SJF)으로 CPU 이양 방식 구분
- **타임 슬라이스** 크기와 문맥 전환 비용·응답성 간 상충 관계
- 장기 대기 프로세스의 **기아 현상** 방지를 위한 에이징(Aging) 메커니즘 필요

#### 한줄 요약

- 선점형은 응답성이 높지만 문맥 전환 비용이 크고, 비선점형은 오버헤드가 낮지만 호위 효과로 응답시간 악화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 실행 시간(Virtual Runtime, vruntime)**: CFS에서 프로세스의 실제 실행 시간에 우선순위 가중치를 반영하여 산출하는 공정 배분 기준값.
- **레드-블랙 트리(Red-Black Tree)**: CFS가 vruntime 순으로 프로세스를 정렬·관리하는 자가 균형 이진 탐색 트리로, 최소 vruntime 프로세스를 O(log n)에 선정.
- **디스패처(Dispatcher)**: 스케줄러가 선정한 프로세스의 문맥을 복원하고 CPU를 넘기는 커널 모듈.

</details>

```text
[ 프로세스 스케줄링 구조 ]
준비 큐 (Ready Queue)
├─ FCFS·SJF: FIFO 연결 리스트
├─ RR: 순환 큐 (Circular Queue)
├─ MLFQ: 다단계 우선순위 큐
└─ CFS: vruntime 기반 레드-블랙 트리
커널 스케줄러
├─ 정책 적용 (우선순위·vruntime 기반 선정)
└─ 디스패처 (문맥 복원·CPU 이양)
하드웨어 타이머 (타임 슬라이스 만료 시 인터럽트)
```

선의 의미: 가지(`├─`, `└─`)는 스케줄러가 알고리즘별로 준비 큐를 관리하고 디스패처에게 선정 결과를 전달하는 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 준비 큐 | 알고리즘 방식에 맞는 자료 구조로 **PCB** 대기 |
| 커널 스케줄러 | 정책 기반으로 다음 실행 프로세스 **PCB** 선정 |
| 디스패처 | 선정 프로세스 문맥 복원 및 **CPU 이양** |
| 하드웨어 타이머 | **타임 슬라이스** 만료 시 선점 인터럽트 발생 |

#### 한줄 요약

- 스케줄러가 준비 큐에서 정책 기반으로 다음 프로세스를 선정하면 디스패처가 문맥을 복원해 CPU를 넘김

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **에이징(Aging)**: 대기 시간이 길어질수록 프로세스의 우선순위를 점진적으로 높여 기아 현상을 방지하는 기법.

</details>

```text
프로세스 대기 (Ready Queue)
   │
   ▼
1. 준비 큐 갱신 (에이징·우선순위 재계산)
   │
   ▼
2. 스케줄러: 다음 실행 프로세스 선정
   │
   ▼
3. 디스패처: 문맥 복원·CPU 이양 (타임 슬라이스 부여)
   │
   ├─ 자발적 반납 (I/O 대기·종료): 준비 큐로 이동
   └─ 타임 슬라이스 만료: 선점 인터럽트
         │
         ▼
      4. 문맥 저장 후 준비 큐 복귀 → 1단계 반복
```

**동작 원리**

1. **준비 큐 갱신**: 대기 중 프로세스에 **에이징** 적용하여 우선순위를 재계산
2. **스케줄러 선정**: 알고리즘(최소 vruntime·최고 우선순위·FIFO)에 따라 다음 실행 프로세스 결정
3. **디스패처 실행**: 선정 프로세스의 **PCB**에서 문맥을 복원하고 **타임 슬라이스** 활용 부여하여 CPU 이양
4. **선점 처리**: 타이머 인터럽트 발생 시 현재 프로세스 문맥을 저장하고 준비 큐로 복귀

#### 한줄 요약

- 에이징으로 큐를 갱신하고 정책에 따라 선정 후 디스패처가 실행하며, 시간 만료 시 선점하여 반복

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MLFQ(Multi-Level Feedback Queue)**: 준비 큐를 우선순위 계층으로 나누고, CPU 집약 작업은 하위 큐로 강등·I/O 완료 후 복귀하는 적응형 스케줄러.
- **나이스 값(Nice Value)**: 리눅스에서 프로세스의 CFS 가중치를 조정하는 값(-20~19)으로, 낮을수록 CPU를 더 많이 할당.

</details>

| 구분 | FCFS | SJF | RR | MLFQ | CFS |
|:---|:---|:---|:---|:---|:---|
| 적용 기준 | 구현 단순성 우선 시 | 대기시간 최소화 시 | 공정 응답성 필요 시 | I/O·CPU 혼합 워크로드 시 | 범용 Linux 멀티태스킹 |
| 핵심 특징 | 도착 순서 비선점 처리 | 실행시간 최단 우선 | **타임 슬라이스** 순환 | 다단계 큐 동적 강등·승격 | **vruntime** 기반 공정 배분 |
| 한계 | **호위 효과** 발생 | **기아 현상** 발생 | 잦은 문맥 전환 오버헤드 | 튜닝 파라미터 복잡성 | **나이스 값** 오설정 시 불공정 |

#### 한줄 요약

- 범용 응답성은 CFS·MLFQ, 최단 대기는 SJF, 단순 배치는 FCFS, 공정 순환은 RR 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 가용률(CPU Utilization)**: 전체 실행 시간 중 실제 프로세스 코드를 실행하는 비율로, 문맥 전환 오버헤드가 증가할수록 가용률이 감소.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 우선순위 스케줄링에서 저우선순위 프로세스 **기아 현상** 발생 | 대기 시간 비례 **에이징** 기반 우선순위 동적 상향 | **기아 현상** 원천 차단 |
| 짧은 **타임 슬라이스** 기반 문맥 전환 급증·**CPU 가용률** 저하 | 응답 목표를 고려한 **타임 슬라이스** 크기 튜닝 | 문맥 전환 오버헤드 감소 및 가용률 회복 |
| 단일 프로세스의 CPU 독점으로 전반 응답성 저하 | **나이스 값** 조정으로 **vruntime** 가중치 제어 | 특정 프로세스 독점 억제 |

#### 한줄 요약

- 기아는 에이징으로, 전환 오버헤드는 타임 슬라이스 튜닝으로, CPU 독점은 나이스 값으로 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스케줄링 알고리즘 선택 기준**: 대화형 응답성·처리량·공정성·실시간 기한 보장 중 우선 요구에 따라 알고리즘을 결정하는 판단 기준.

</details>

- 범용 대화형 시스템은 **CFS/MLFQ**, 마감 기한 엄격 제어 요구는 **실시간(RT) 스케줄러** 선택

#### 한줄 요약

- 응답성·공정성 우선이면 CFS나 MLFQ, 마감 기한 엄격 보장이 필요하면 실시간 스케줄러를 선택
