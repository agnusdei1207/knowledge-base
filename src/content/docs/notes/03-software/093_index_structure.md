## 미리 알고가기

- **인덱스 (Index)**: 검색 키로 테이블 행에 접근하는 보조 구조임
- **선택도 (Selectivity)**: 조건이 전체 행을 좁히는 정도임
- **B+트리 (B+Tree)**: 정렬 키로 점·범위 탐색을 지원함
- **해시 인덱스 (Hash Index)**: 해시값으로 등치 키를 탐색함
- **복합 인덱스 (Composite Index)**: 여러 컬럼을 순서대로 묶은 인덱스임
- **옵티마이저 (Optimizer)**: 통계로 실행 경로를 선택함
- **데이터베이스 (Database, DB)**: 구조화 데이터를 저장·관리함
- **95백분위 지연 (95th Percentile Latency, p95)**: 요청 95%가 완료되는 지연 기준임
- **테이블 전체 읽기(Full Table Scan)**: 조건에 맞는 행을 찾기 위해 테이블의 모든 행을 읽는 방식임
- **등치 조건(Equality Predicate)**: 열의 값이 지정한 값과 같은지를 검사하는 조건임
- **범위 조건(Range Predicate)**: 열의 값이 시작값과 끝값 사이인지 검사하는 조건임
- **선두 열(Leading Column)**: 복합 인덱스에서 가장 먼저 정렬되어 탐색 시작점을 정하는 열임
- **페이지 분할(Page Split)**: 꽉 찬 인덱스 페이지에 값을 넣기 위해 내용을 둘로 나누는 작업임
- **실행 계획(Execution Plan)**: 데이터베이스가 질의를 처리하기 위해 선택한 연산 순서와 접근 경로임

## Ⅰ. 개요

- **정의/개념**: 검색 키로 행의 접근 경로를 제공함
- **배경/필요성**: 전체 테이블 탐색 지연으로 색인 구조 필요

### 쉽게 이해하기 (학습용)
- 책 전체를 넘기지 않고 색인에서 단어를 찾아 해당 쪽으로 바로 이동하게 하는 구조임

## Ⅱ. 특징

- B+트리는 범위 검색과 정렬에 쓰이는 범용 구조다.
- 해시 인덱스는 등치 조회에 맞고 범위 탐색에는 맞지 않는다.
- 복합 인덱스는 다중 조건에 유리하지만 열 순서에 민감하다.
- 색인 증가는 조회 지연을 줄이지만 쓰기·공간 비용을 늘린다.

### 쉽게 이해하기 (학습용)
- 찾기는 빨라지지만 색인이 많을수록 새 내용을 쓸 때마다 색인도 함께 고쳐야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 검색 키 | 대상 컬럼과 복합 키 순서를 정함 |
| 탐색 구조 | 정렬 트리나 해시로 탐색 방식을 정함 |
| 행 위치 | 인덱스 결과를 실제 테이블 행과 연결함 |
| 통계 정보 | 선택도와 분포로 인덱스 사용을 판단함 |

```text
  패턴통계
      ↓
  순서선정
      ↓
  구조탐색
      ↓
  결과연결
```

> 요약: 검색 키와 탐색 구조 및 통계가 조회 경로를 결정함

### 쉽게 이해하기 (학습용)
- 검색 키 순서와 탐색 구조가 행 접근 경로를 정함

## Ⅳ. 원리 및 절차 흐름도

```text
  패턴수집
      ↓
  구조선택
      ↓
  순서설계
      ↓
  비용검증
```

| 절차 | 설명 |
|:---|:---|
| 패턴수집 | 조회 조건과 정렬 및 빈도를 수집함 |
| 구조선택 | 등치와 범위 조건으로 탐색 구조를 정함 |
| 키순서설계 | 조건과 정렬 순서로 복합 키를 구성함 |
| 비용검증 | 조회 이득과 쓰기 및 저장 비용을 확인함 |

> 요약: 질의 패턴에 맞춰 구조와 키 순서 및 비용을 검증함

### 쉽게 이해하기 (학습용)
- 질의 패턴에 맞춘 인덱스 조회 이득과 쓰기 비용을 검증함

## Ⅴ. 종류 및 비교

| 비교축 | B+Tree | 해시 인덱스 | 복합 인덱스 |
|:---|:---|:---|:---|
| 핵심 특징 | 정렬 트리 기반 탐색 구조임 | 해시 함수 기반 탐색 구조임 | 여러 컬럼을 묶는 키 구성임 |
| 적용 기준 | 범위와 정렬 조회에 적용함 | 전체 키의 등치 조회에 적용함 | 여러 컬럼 조건 조회에 적용함 |
| 주요 위험 | 페이지 분할과 키 분포를 관리함 | 범위 조회와 정렬에 부적합함 | 선두 컬럼 순서에 민감함 |

> 요약: 트리는 탐색 구조이고 복합 인덱스는 키 구성임

### 쉽게 이해하기 (학습용)
- 트리는 범위에 맞추고 해시는 등치에 맞추며 복합 키는 다중 조건에 맞춤

## Ⅵ. 실무 사례

1. 주문 조회 시스템은 복합 인덱스를 적용하고 지연을 확인함
2. 쓰기 집약 시스템은 인덱스를 제거하고 쓰기 지연을 확인함

### 쉽게 이해하기 (학습용)
- 주문 목록의 조건과 정렬 순서에 맞춘 복합 인덱스는 읽는 행 수와 응답 지연을 줄일 수 있음
- 쓰기가 많은 시스템은 사용하지 않는 인덱스를 제거해 매 변경마다 발생하는 인덱스 갱신 비용을 줄일 수 있음

## Ⅶ. 결론

- 질의 패턴에 맞는 구조·키 순서·개수 설계

### 쉽게 이해하기 (학습용)
- 인덱스는 실제 실행 계획의 조회 이득이 쓰기·저장 비용보다 큰 경우에만 유지해야 함
