## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **VEX (Vulnerability Exploitability eXchange)**: SBOM에 명시된 컴포넌트의 CVE 취약점이 실제 실행 환경에서 악용 가능한지(Reachability) 여부와 상태를 명세하는 보안 표준.
- **Reachability Analysis(도달성 분석)**: 정적/동적 호출 그래프(Call Graph)를 추적하여 취약한 함수가 실제 비즈니스 로직 실행 경로에 도달하는지 검증하는 기술.

</details>

- 정의/개념: SBOM에 포함된 오픈소스 컴포넌트의 취약점(CVE)이 **실제 실행 환경에서 악용 가능한지 영향도와 상태를 명세하는 보안 교환 규격**
- 배경/필요성: 버전 매칭만으로 스캔하면 실제로 호출되지 않는 코드의 취약점까지 경보로 올라와 검증·패치 공수가 경보 수만큼 낭비되므로, 스캔 결과와 대응 사이에 도달성 판정을 명시하는 계층을 두어 대응할 대상만 남길 필요

#### 한줄 요약
- 도달성 분석을 기반으로 취약점의 실제 악용 가능 여부를 판정하여 보안 패치 우선순위를 최적화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **4대 Product Status**: Affected(영향 있음), Not Affected(영향 없음), Fixed(패치 완료), Under Investigation(조사 중).
- **Justification**: `not_affected` 판정 시 `code_not_reachable`(함수 미호출) 등 객관적 기술 근거를 명시하는 필드.

</details>

- 취약점의 실제 영향 여부를 명확히 구분하는 **4가지 표준 상태(Product Status)**
- '영향 없음' 판정 시 객관적 근거를 제시하는 **정당화 사유(Justification: 코드 미도달 등)**
- CSAF 및 CycloneDX 규격을 통한 **기계 판독 자동화 및 DevSecOps CI/CD 연동**

#### 한줄 요약
- 4대 상태 판정, 객관적 정당화 근거, 기계 판독 자동화를 통해 오탐을 제거한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **VEX 4대 데이터 모델**: Product ID(대상 제품 purl), Vuln ID(CVE 번호), Product Status(영향 상태), Justification/Evidence(판단 근거).

</details>

```text
[VEX 구성]
|-- 제품 식별자
|-- 취약점 식별자
|-- 제품 상태
`-- 정당화 근거
```

선의 의미: 계층 및 제품과 CVE 취약점을 매핑하여 4대 상태 중 하나를 부여하고 Not Affected일 경우 정당화 근거를 첨부하는 구조

| 구성요소 | 책임 | 주요 특징 |
|:---|:---|:---|
| 제품 식별자 | 버전·해시·**purl**로 대상 제품 특정 | 고유 식별 체계 |
| 취약점 식별자 | **CVE·NVD 식별자**로 취약점 특정 | CVE-YYYY-NNNN |
| 제품 상태 | **Affected·Not Affected·Fixed·조사 중** 표현 | 4대 표준 상태 |
| 정당화 근거 | Not Affected의 **도달성 증거** 명시 | 객관적 증적 |

#### 한줄 요약
- 제품·취약점 식별자가 판정의 적용 범위를 고정하고 정당화 근거가 그 판정의 책임을 남기므로, 영향 없음 선언이 근거 없는 면책으로 쓰이지 못한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **VEX 도달성 분석 및 조치 5단계**: 취약점 탐지 $\to$ 호출 그래프 도달성 분석 $\to$ 상태 판정 $\to$ 근거 작성/패치 $\to$ VEX 문서 전자서명 및 배포.

</details>

```text
SBOM 기반 신규 CVE 취약점 발견
        │
   1. [취약점 탐지] 사내 소프트웨어 SBOM에 포함된 오픈소스 라이브러리에서 CVE 탐지
        │
   2. [도달성 분석] SAST 도구가 호출 그래프(Call Graph)를 분석하여 취약 함수 실제 호출 여부 검증
   ┌────┴───────────────────────────┐
  not_affected (함수 미호출)        affected (함수 실제 호출)
   │                                 │
3A. [정당화 근거 작성]              3B. [긴급 패치 개발]
   `code_not_reachable` 기재            보안 패치 및 라이브러리 업그레이드
   │                                 │
   └────┬────────────────────────────┘
        ▼
   4. CSAF / CycloneDX 표준 JSON VEX 문서 생성 및 보안 책임자 전자서명(Cosign)
        │
   5. 고객사 및 내부 운영팀에 VEX를 배포하여 불필요한 패치 작업을 중단하고 진짜 위협에 집중
```

#### 한줄 요약
- 비용이 갈리는 지점은 도달성 분석이며, 영향 없음으로 판정되면 근거 작성 비용만 남지만 영향 있음이면 패치와 재배포까지의 전체 공수가 발생한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CSAF vs CycloneDX VEX**: OASIS 전용 보안 권고 독립 문서 포맷(CSAF)과 OWASP SBOM 일체형 경량 포맷(CycloneDX).

</details>

| 비교 항목 | CSAF VEX (OASIS 표준) | CycloneDX VEX (OWASP 표준) |
|:---|:---|:---|
| 핵심 지향점 | **독립된 보안 권고(Security Advisory) 발행** | **DevSecOps 파이프라인 및 SBOM 일체형 검증** |
| 문서 결합 방식 | **SBOM과 분리된 독립 JSON 권고문 파일** | **SBOM 문서 내에 VEX 메타데이터 직접 임베딩** |
| 표준화 기구 | **OASIS (Common Security Advisory Framework)**| **OWASP (Open Web Application Security Project)**|
| 최적 적용 분야 | **글로벌 소프트웨어 벤더의 대고객 보안 권고문** | **CI/CD 빌드 파이프라인 내 실시간 취약점 필터링** |

#### 한줄 요약
- 대고객 권고는 CSAF VEX, 빌드 파이프라인 내장 처리는 CycloneDX VEX를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Evidence-based VEX**: 개발팀의 책임 회피성 허위 '영향 없음' 선언을 방지하기 위해 호출 그래프 스캔 증적과 보안팀 전자서명을 의무화하는 통제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 개발팀의 패치 회피를 위한 무단 `not_affected` 허위 선언 | **도달성 호출 그래프(Call Graph) 증적 및 보안팀 전자서명 의무화** | 허위 판정 원천 차단 |
| 소프트웨어 버전 업데이트 시 이전 VEX 문서가 잘못 적용됨 | **`purl` 및 빌드 SHA-256 해시 기반의 1:1 불변 결속 검증** | 버전 불일치로 인한 보안 누락 방지 |
| `fixed` 상태로 VEX를 발행했으나 실제 릴리즈 배포가 누락됨 | **배포 파이프라인(CD)과 VEX 릴리즈 상태를 자동 동기화** | 미패치 제품 배포 사고 방지 |
| 신규 CVE 발생 시 분석 지연으로 인한 보안 공백 | **초기 상태를 `under_investigation`으로 선언 후 24시간 내 분석** | 취약점 관리 가시성 유지 |

#### 한줄 요약
- 네 대책은 패치를 건너뛰는 판정에 증적과 서명, 버전 결속을 요구해 절감된 공수만큼의 책임을 되돌려 놓는 장치다.

## Ⅶ. 결론

- 패치 우선순위는 **도달성 분석**, 오탐 제거는 **VEX** 선택

#### 한줄 요약
- VEX는 도달성 분석과 4대 표준 상태 명세를 통해 거짓 양성(False Positive)을 제거하고 실질적 위험에 신속히 대응하도록 지원하는 핵심 소프트웨어 공급망 보안 기술이다.
