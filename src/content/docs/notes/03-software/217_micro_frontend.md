## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Micro Frontend (MFE)**: 모놀리식 프론트엔드 애플리케이션을 비즈니스 도메인 단위의 독립된 마이크로 앱으로 분할하고 런타임에 단일 화면으로 조합하는 아키텍처.
- **Module Federation (모듈 페더레이션)**: Webpack 5에서 도입된 기술로, 여러 독립 빌드된 원격 번들을 런타임 브라우저에서 동적으로 가져와 결합하는 기술.

</details>

- 정의/개념: 모놀리식 프론트엔드를 비즈니스 도메인별 마이크로 앱으로 분할하고 **애플리케이션 셸(Shell)을 통해 통합하여 독립 배포를 실현하는 UI 아키텍처**
- 배경/필요성: 백엔드가 마이크로서비스(MSA)로 분할되었음에도 프론트엔드가 거대한 단일 SPA(Single Page Application) 모놀리스로 남아 수십 개 팀의 배포 일정이 단일 릴리즈 파이프라인에 병목되고 사소한 자바스크립트 런타임 오류가 전체 웹페이지 백화 현상으로 번지는 구조적 한계를 극복하기 위해, 프론트엔드 화면을 비즈니스 도메인별 마이크로 앱으로 분할하고 애플리케이션 셸(Shell)과 웹팩 모듈 페더레이션(Module Federation)을 통해 런타임 통합하는 마이크로프론트엔드(MFE) 아키텍처를 도입하여 **팀별 100% 자율 독립 배포와 에러 바운더리(Error Boundary) 기반 장애 격리를 실현**할 필요

#### 한줄 요약
- 비즈니스 도메인 단위로 프론트엔드를 분할하여 팀별 독립 개발과 무중단 자율 배포를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Application Shell (애플리케이션 셸)**: 전역 내비게이션, 헤더/푸터, 사용자 인증 세션, 마이크로 앱 동적 로딩을 전담하는 공통 컨테이너 프레임.
- **Error Boundary**: 특정 마이크로 앱에서 런타임 자바스크립트 크래시가 발생하더라도 전체 페이지 다운 없이 해당 영역만 대체 UI로 격리하는 보호막.

</details>

- 도메인별 전담 팀이 독립된 Git 리포지토리와 파이프라인을 소유하는 **독립 개발 및 자율 배포**
- 전역 라우팅과 사용자 인증 세션을 중앙 관리하는 **애플리케이션 셸(Shell) 컨테이너**
- 특정 마이크로 앱의 런타임 오류가 전체 화면으로 전파되지 않는 **Error Boundary 장애 격리**

#### 한줄 요약
- 독립 배포, 애플리케이션 셸, Error Boundary 장애 격리를 통해 프론트엔드 민첩성을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **마이크로프론트엔드 4대 아키텍처**: Application Shell(라우팅/인증), Micro Apps(도메인 UI), Integration Contract(이벤트 버스), Design System(공통 UI 토큰).

</details>

```text
[마이크로프론트엔드]
|-- 애플리케이션 셸
|-- 비즈니스 마이크로 앱
|-- 통합 계약
|-- 디자인 시스템
`-- 에러 바운더리
```

선의 의미: 계층 및 애플리케이션 셸이 라우팅에 따라 도메인별 마이크로 앱을 동적으로 로드하고 공통 이벤트 버스와 디자인 시스템으로 결합하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **애플리케이션 셸** | 라우팅·레이아웃·앱 수명주기 통제 |
| **비즈니스 마이크로 앱** | 도메인 UI와 독립 배포 소유 |
| **통합 계약** | 앱 간 이벤트와 상태 통신 규약 |
| **디자인 시스템** | 공통 토큰과 UI 일관성 제공 |
| **에러 바운더리** | 앱 오류 격리와 폴백 UI 제공 |

#### 한줄 요약
- 셸이 조합과 수명주기를 맡고 각 앱은 자기 도메인만 소유하므로, 배포 자율성은 통합 계약과 디자인 시스템이 대신 감당하는 일관성 비용으로 산 것이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마이크로 앱 로딩 5단계**: URL 라우팅 변경 감지 $\to$ 원격 JS 번들 비동기 인출 $\to$ DOM 마운트 및 이벤트 바인딩 $\to$ 조합 화면 렌더링 $\to$ 에러 발생 시 폴백 격리.

</details>

```text
[화면 이동 요청]
       |
1. 라우팅 감지
       |
2. 원격 번들 인출
       |
3. 앱 마운트
       |
   [렌더링 성공?]
    /       \
  예        아니오
  |           |
4. 화면 조합  폴백 격리
  |
[통합 화면 응답]
```

- 1. 라우팅 감지: 셸이 대상 **마이크로 앱** 식별
- 2. 원격 번들 인출: 런타임 모듈 로딩
- 3. 앱 마운트: 지정 DOM과 이벤트 계약 결합
- 4. 화면 조합: 성공 UI 또는 **폴백 UI** 표시

#### 한줄 요약
- 번들을 런타임에 가져오기 때문에 배포 독립성을 얻는 대신 초기 로딩에 네트워크 왕복이 더해지며, 에러 바운더리가 그 실패를 전체가 아닌 화면 일부로 가둔다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MFE 3대 조합 방식**: 빌드 시 조합(Build-Time), 런타임 조합(Client-Side Runtime), 엣지/서버 조합(Edge/SSR).

</details>

| 비교 항목 | 빌드 시 조합 (Build-Time) | 런타임 조합 (Runtime / Webpack) | 엣지/서버 조합 (Edge/SSR) |
|:---|:---|:---|:---|
| 핵심 조합 시점 | **NPM 패키지 형태로 빌드 시 정적 번들링** | **브라우저 실행 중 원격 모듈 비동기 로딩** | **CDN/Nginx 리버스 프록시 서버에서 HTML 조합** |
| 독립 배포 자율성 | 낮음 (앱 수정 시 셸 전체 재빌드 필요) | **최고 (각 팀이 수시로 독립 무중단 배포)**| 높음 (각 서비스별 SSR 서버 독립 배포) |
| 초기 렌더링 성능 | 보통 (단일 대형 번들 다운로드) | 약간 지연 (동적 모듈 로딩 레이턴시) | **최상 (서버에서 완성된 HTML 응답, SEO 최적)**|
| 최적 적용 사례 | 소규모 팀의 모노레포 프로젝트 | **대규모 팀의 독립 SPA 웹 서비스 전반** | 검색 엔진 최적화(SEO)가 필수인 e커머스 |

#### 한줄 요약
- 단순 패키지는 빌드 시 조합, 자율 독립 배포는 런타임 조합, SEO와 초기 성능은 엣지/서버 조합을 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Shared Dependencies**: 리액트(React) 등 대용량 공통 라이브러리를 각 마이크로 앱이 중복 다운로드하지 않고 싱글톤(Singleton)으로 공유하는 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중복 라이브러리(React 등) 다운로드로 번들 크기 폭증 | **Module Federation `shared: { react: { singleton: true } }` 강제** | 초기 다운로드 페이로드 60% 절감 |
| 팀별 CSS 프레임워크 충돌로 화면 스타일 오염 현상 | **`CSS Modules, Tailwind, Shadow DOM` 기반 스타일 스코프 격리** | 스타일 간섭 및 UI 깨짐 완벽 방지 |
| 특정 마이크로 앱 스크립트 에러로 전체 웹페이지 백화 | **각 마이크로 앱 마운트 지점에 `React Error Boundary` 필수 적용** | 런타임 오류 격리 및 서비스 가용성 사수 |
| 마이크로 앱 간 과도한 직접 호출로 강결합 발생 | **직접 참조를 금지하고 `CustomEvent 기반 브라우저 이벤트 버스` 통신** | 팀 간 의존성 최소화 및 느슨한 결합 |

#### 한줄 요약
- 네 대책은 앱을 쪼개 얻은 자율성의 대가인 중복 번들·스타일 충돌·강결합을 공유 의존성과 격리 규약으로 되사는 선택이다.

## Ⅶ. 결론

- 대규모 조직에서 백엔드 MSA와 프론트엔드 개발 조직의 온전한 콘웨이 법칙(Conway's Law) 정렬을 달성하는 **가장 핵심적인 엔터프라이즈 프론트엔드 아키텍처 표준 패러다임**으로 정립되었으며, 실무 구축 시에는 **Webpack 5 Module Federation 기반 런타임 동적 조합, 공통 React 라이브러리 싱글톤(Shared Dependencies) 공유를 통한 번들 최적화, Shadow DOM/CSS Modules를 활용한 스타일 오염 차단, React Error Boundary 기반 국소 장애 격리, CustomEvent 브라우저 이벤트 버스를 통한 느슨한 결합**을 결합하여 자율성과 일관된 사용자 경험(UX)을 완벽히 조화

#### 한줄 요약
- 마이크로프론트엔드는 도메인별 화면 분할과 런타임 조합을 통해 팀별 자율 독립 배포와 장애 격리를 실현하는 핵심 웹 아키텍처 기술이다.
