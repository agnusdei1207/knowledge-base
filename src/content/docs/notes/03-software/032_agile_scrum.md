## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **스크럼(Scrum)**: 짧은 스프린트마다 사용 가능한 제품 증분을 만들어 복잡한 문제에 대응하는 경량 프레임워크이다.
- **경험주의(Empiricism)**: 실제 결과를 투명하게 공개하고 점검한 뒤 다음 행동에 적응하는 접근이다.
- **제품 증분(Increment)**: 완료의 정의를 충족해 사용할 수 있는 제품 결과이다.

</details>

- 정의/개념: **스크럼**은 **경험주의**에 따라 스프린트마다 **제품 증분**을 만드는 경량 프레임워크이다.
- 배경/필요성: 장기 계획은 잦은 요구 변화와 늦은 검증으로 재작업을 증가시킨다.

#### 한줄 요약

- 짧은 스프린트와 **제품 증분**을 통한 **경험주의**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **투명성(Transparency)**: 실제 작업 상태를 이해관계자에게 공개하는 원칙이다.
- **점검(Inspection)**: 제품과 진행 결과를 주기적으로 살피는 원칙이다.
- **적응(Adaptation)**: 점검 결과에 따라 계획과 행동을 바꾸는 원칙이다.
- **스프린트(Sprint)**: 고정된 짧은 기간에 목표와 사용 가능한 제품 증분을 완성하는 반복 주기이다.
- **교차기능(Cross-functional)**: 팀이 제품 완성에 필요한 기술을 함께 갖춘 성질이다.
- **자율관리(Self-managing)**: 팀이 작업 담당과 방법을 스스로 정하는 성질이다.

</details>

- **투명성**, **점검**, **적응**으로 실제 결과에 따라 계획을 조정한다.
- **스프린트**마다 사용 가능한 제품 증분을 생성한다.
- **교차기능**과 **자율관리**를 갖춘 팀이 제품 목표 달성 책임을 공유한다.

#### 한줄 요약

- **투명성**, **점검**, **적응**으로 제품과 팀의 효과성을 개선한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **제품 책임자(Product Owner)**: 제품 가치와 제품 백로그의 우선순위를 책임지는 역할이다.
- **스크럼 마스터(Scrum Master)**: 스크럼 정착과 팀 효과성 향상, 장애물 제거를 지원하는 역할이다.
- **제품 백로그(Product Backlog)**: 제품에 필요한 작업을 우선순위로 관리하는 목록이다.
- **스프린트 백로그(Sprint Backlog)**: 현재 스프린트의 목표와 실행 계획을 관리하는 목록이다.
- **완료의 정의(Definition of Done)**: 제품 증분이 충족해야 하는 공통 품질 기준이다.

</details>

```text
[제품 책임자] -- [제품•스프린트 백로그] -- [개발자] -- [제품 증분]
                                          |
                                   [스크럼 마스터]
```

선의 의미: 제품 책임자는 제품•스프린트 백로그를 관리하고, 개발자는 백로그를 바탕으로 제품 증분을 만들며, 스크럼 마스터는 개발자의 효과적인 수행을 지원한다.

| 구성요소 | 책임 |
|:---|:---|
| 제품 책임자 | **제품 책임자**가 제품 가치와 **제품 백로그** 관리 |
| 스크럼 마스터 | **스크럼 마스터**가 스크럼 정착과 팀 효과성 향상 지원 |
| 개발자 | 스프린트 계획•제품 증분 완성 |
| 제품•스프린트 백로그 | 제품의 장기 작업과 **스프린트 백로그**의 반복 계획 관리 |
| 제품 증분 | **완료의 정의**를 충족한 결과 제공 |

#### 한줄 요약

- **제품 책임자**, **스크럼 마스터**, **제품 백로그**, **스프린트 백로그**, **완료의 정의**가 역할과 산출물을 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **스프린트 계획(Sprint Planning)**: 제품 백로그에서 목표와 이번 반복의 실행 범위를 정하는 이벤트이다.
- **스프린트 목표(Sprint Goal)**: 한 스프린트에서 달성할 단일 목적이자 작업 조정 기준이다.
- **일일 스크럼(Daily Scrum)**: 개발자가 목표 진행 상황을 점검하고 다음 작업 계획을 조정하는 이벤트이다.
- **스프린트 리뷰(Sprint Review)**: 이해관계자와 제품 결과•환경 변화•다음 작업을 검토하는 이벤트이다.
- **스프린트 회고(Sprint Retrospective)**: 팀의 품질과 효과성을 높일 개선 행동을 정하는 이벤트이다.
- **스프린트 실행**: 스프린트 목표에 맞춰 개발•통합•시험을 수행하는 단계이다.
- **완료의 정의 검증**: 제품 증분이 공통 품질 기준을 충족했는지 확인하는 단계이다.

</details>

```text
┌──────────────────────────────┐
│ 제품 백로그                │◀──────────────┐
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 1. 스프린트 계획           │               │
│ 목표•스프린트 백로그       │               │
└──────────────┬───────────────┘               │
               ▼                               │
╔══════════════════════════════╗               │
║ 2. 스프린트 실행           ║               │
║ 일일 스크럼•통합•시험      ║               │
╚══════════════╤═══════════════╝               │
               ▼                               │
┌──────────────────────────────┐               │
│ 3. 완료의 정의 검증        │               │
└───────┬──────────────────────┘               │
        ├─ 미충족 ─▶ [백로그 반환] ────────────┘
        │ 충족                                  │
        ▼                                       │
┌──────────────────────────────┐               │
│ 4. 스프린트 리뷰           │               │
│ 제품•환경•백로그 피드백    │               │
└──────────────┬───────────────┘               │
               ▼                               │
┌──────────────────────────────┐               │
│ 5. 스프린트 회고           │               │
│ 팀 개선 행동 확정          │───────────────┘
└──────────────────────────────┘
```

### 동작 원리

1. **스프린트 계획**으로 **스프린트 목표**와 반복 범위•실행 계획을 확정한다.
2. **스프린트 실행** 중 **일일 스크럼**과 통합•시험을 수행한다.
3. **완료의 정의 검증**으로 증분의 공통 품질 기준을 확인한다.
4. **스프린트 리뷰**로 제품 결과와 다음 백로그를 조정한다.
5. **스프린트 회고**로 팀 효과성 개선 행동을 확정한다.

#### 한줄 요약

- **스프린트 계획**부터 **스프린트 회고**까지의 순환이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **전통 프로젝트(Traditional Project)**: 장기 요구 기준선과 단계별 산출물 승인을 중심으로 진행하는 관리 방식이다.
- **제품 피드백**: 실제 제품 증분의 사용성과 가치를 검토해 백로그 순서에 반영하는 의견이다.

</details>

| 개발 관리 방식 | 애자일 스크럼 | 전통 프로젝트 |
|:---|:---|:---|
| 적용 기준 | 변화•**제품 피드백** 중심 | 요구 안정•승인 통제 중심 |
| 핵심 특징 | 스프린트•제품 증분 | **전통 프로젝트**의 장기 기준선•단계별 산출물 |
| 한계 | 목표 변경•행사 형식화 | 늦은 피드백•재작업 |

> 요약: 스크럼은 짧은 증분, 전통 방식은 단계 기준선으로 통제한다.

#### 한줄 요약

- 변화•제품 피드백은 **스크럼**, 승인 통제는 전통 방식이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **기술 부채(Technical Debt)**: 미룬 설계•시험•품질 작업이 이후 변경 비용으로 누적된 상태이다.
- **품질 게이트(Quality Gate)**: 시험•보안•코드 품질 기준을 충족해야 제품 증분 통합을 허용하는 통제이다.
- **장애물(Impediment)**: 스크럼 팀의 목표 달성이나 작업 흐름을 막는 문제이다.
- **백로그 결정 규칙**: 제품 가치•위험•목표를 기준으로 제품 책임자가 항목의 순서를 확정하는 규칙이다.
- **범위 재협의(Scope Renegotiation)**: 스프린트 목표를 유지하면서 제품 책임자와 개발자가 선택 작업의 양•내용을 다시 조정하는 활동이다.
- **리뷰 결정(Review Decision)**: 제품과 백로그 변경을 확정한 결과이다.
- **회고 행동(Retrospective Action)**: 팀 개선 과제와 책임자를 확정한 결과이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제품 책임자의 우선순위 권한 분산으로 상충 지시 발생 | 단일 제품 책임자와 **백로그 결정 규칙** 명시 | 제품 목표별 우선순위 일관성 유지 |
| 스프린트 중 잦은 범위 변경으로 목표 상실 | 스프린트 목표 보호•**범위 재협의** | 스프린트의 증분 범위 유지 |
| 약한 완료의 정의로 시험 누락•**기술 부채** 누적 | 자동 시험•보안•문서•**품질 게이트** 포함 | 실제 사용 가능한 제품 증분 확보 |
| 스크럼 이벤트가 보고 회의로 형식화되거나 **장애물**이 방치됨 | **리뷰 결정**•**회고 행동**•장애물 책임자 기록 | 점검 결과의 적응 행동 실행 |

#### 한줄 요약

- **품질 게이트**, **리뷰 결정**, **회고 행동**의 실행성을 확보한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **백로그 재정렬**: 제품 가치•위험•피드백에 맞춰 다음 작업의 우선순위를 다시 정하는 활동이다.
- **기술 부채 해소**: 완료 기준에 못 미친 설계•시험•품질 작업을 우선 수행해 변경 비용을 줄이는 활동이다.
- **백로그 우선순위 결정 기준**: 스프린트 목표와 완료의 정의 충족 여부를 바탕으로 가치 작업과 기술 부채 해소 순서를 정하는 기준이다.

</details>

- 스프린트 목표와 **완료의 정의**를 충족하면 **백로그 재정렬**, 미달하면 **기술 부채 해소**를 우선하는 것이 **백로그 우선순위 결정 기준**이다.

#### 한줄 요약

- 목표•완료 기준 충족 여부를 함께 평가하는 것이 핵심이다.
