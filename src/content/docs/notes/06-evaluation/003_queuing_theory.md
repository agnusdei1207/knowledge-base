## Ⅰ. 개요

<details><summary>핵심 용어(Core Terms)</summary>

- **대기행렬 이론(Queuing Theory)**: 요청 유입과 서버 처리 능력을 확률 모델화하여 시스템 혼잡도와 대기시간을 수학적으로 분석하는 이론.
- **도착률($\lambda$, Arrival Rate)**: 단위 시간당 시스템 유입 평균 요청 건수.
- **서비스율($\mu$, Service Rate)**: 단위 시간당 단일 서버의 평균 처리 완료 건수.
- **대기 급증(Non-linear Queue Growth)**: 유입 부하가 처리 능력을 초과할 때 대기 지연이 지수적으로 폭증하는 현상.

</details>

- 정의: 가변적 도착률과 서비스율을 통계적으로 모델링하여, 제한적 자원 환경의 대기시간 및 수용 용량을 수학적으로 예측하는 이론.
- 필요성: 단순 평균 계산으로는 예측 불가능한 트래픽 스파이크 시 임계 돌파 및 비선형적 대기 급증 현상 예방.

#### 한줄 요약

- 고객 요청 유입 속도와 시스템 처리 속도 차이에 따른 대기열 지연 확률 모델링 및 적정 서버 용량 산출 구현.

## Ⅱ. 특징

<details><summary>핵심 용어(Core Terms)</summary>

- **이용률($\rho$, Utilization)**: 전체 서비스 처리 능력 대비 유입되는 도착률 부하가 차지하는 비율로, 혼잡도를 판단하는 척도.
- **안정 조건(Stability Condition)**: 시스템의 장기 유입 부하가 가용 가능한 총 처리 역량 미만으로 유지되어 큐 대기열이 발산하지 않고 통제되는 전제 조건.
- **가정 민감도(Assumption Sensitivity)**: 트래픽 도착 분포, 처리시간 분포 등 이론적 가정에 따라 큐 대기 예측값이 극적으로 변화하는 통계적 속성.
- **얼랑 C(Erlang C)**: 다수 병렬 서버 환경에서, 새 요청이 모든 서버 포화로 인해 즉시 처리되지 못하고 대기열로 밀려날 확률을 도출하는 공식.

</details>

- **이용률**이 시스템 한계점인 1(100%)에 근접할수록 병목 현상에 의해 대기시간이 비선형 그래프 형태로 급격히 증가.
- 큐잉 모형 적용 시 **안정 조건**을 만족하는 범위 내에서만 처리 한계 용량과 투입해야 할 적정 서버 노드 수를 산정 가능.
- 시스템 환경별 **가정 민감도**가 매우 크기 때문에, 실 환경에 부합하는 트래픽 도착/서비스 분포, 큐 용량 크기, 스케줄링 규칙 등을 엄밀히 명시하여 오류 최소화.
- 병렬 확장 구조(Scale-out) 시스템의 대기 발생 확률 및 적정 예비 자원 산출에는 **얼랑 C** 확률 공식을 필수 적용.

#### 한줄 요약

- 서버 이용률이 한계치(100%)에 도달할 때 대기열이 기하급수적으로 폭발하는 비선형적 지연 현상 대비.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어(Core Terms)</summary>

- **Kendall 표기(Kendall's Notation)**: 큐잉 시스템 특성을 규격화하여 도착 분포(A), 서비스 시간 분포(S), 서버 수(c), 시스템 최대 용량(K), 고객 규모(N), 서비스 큐 규율(D) 형식으로 축약 정의하는 표준 국제 기호.
- **M/M/1/M/M/c(Markovian Queuing Models)**: 요청 도착 패턴이 포아송 분포($\lambda$), 서버 처리시간이 지수 분포($\mu$)를 갖는 조건 하의 단일 및 다중 병렬 서버 확률 모형.
- **대기시간($W_q$, Waiting Time in Queue)**: 요청이 큐 진입 후 실제 서버 자원 할당 및 처리가 개시될 때까지 허비한 시간.
- **체류시간($W$, Time in System)**: 인프라 진입 후 큐 대기부터 100% 서비스 완료 응답까지 소요된 총 종단 시간.
- **평균 작업 수($L$, Number in System)**: 관측 시점 기준 시스템 전체 구간 내 대기 및 처리 중인 총 잔존 트랜잭션 수.
- **평균 대기열 길이($L_q$, Number in Queue)**: 대기열 내 순번을 기다리는 평균 요청 건수.
- **FIFO(First In, First Out)**: 먼저 유입된 요청부터 순차적으로 처리하는 대기 규율.
- **병렬 서버 수($c$, Number of Parallel Servers)**: 동일 성능의 서비스율로 트래픽을 분산 처리하는 가용 자원 풀의 노드 개수.
- **대기 확률($P_{wait}$, Probability of Waiting)**: 신규 요청 유입 시 모든 서버가 작업 중이어서 대기열로 이동할 확률.

</details>

```text
대기행렬 모형
├─ 도착 과정 (Arrival Process)
├─ 대기열 (Queue)
├─ 서비스 과정 (Service Mechanism)
├─ 대기 규칙 (Queue Discipline)
└─ 켄달 표기 (A/S/c/K/N/D)
```

가지의 의미: 유입(도착), 저장(대기), 방출(서비스) 메커니즘을 켄달 표기법으로 모델링하는 분석 구조.

| 핵심 구성요소 | 역할 및 모델링 책임 |
|:---|:---|
| 도착 과정 | 시스템 밖에서 유입되는 트래픽 패턴인 **도착률**($\lambda$)의 분포 형태 모델링 정의 |
| 대기열 | 자원 한계로 인한 시스템의 임시 보관 용량 및 가득 찼을 때의 요청 차단(Drop) 정책 설정 |
| 서비스 과정 | 서버별 고유 처리 성능인 **서비스율**($\mu$)과 배치된 **병렬 서버 수**($c$)의 처리 구조 모델링 |
| 대기 규칙 | 큐에 진입한 요청들에 대한 **FIFO**, 우선순위 할당(Priority), 임계 시간 초과로 인한 대기 포기(Reneging) 등 처리 순서 정의 |
| 모형 조건 규격 | 분석 시 가정한 수학적 환경을 **Kendall 표기**로 엄격히 명시하여 수식 적용의 타당성 담보 |

- **M/M/1•M/M/c** 기본 모형을 기반으로 수식을 전개하여, 시스템 운영의 핵심 KPI인 **대기시간**, **체류시간**, **평균 작업 수**, **평균 대기열 길이**, 전체 **대기 확률**을 체계적으로 도출 및 산출.

#### 한줄 요약

- 유입 트래픽 빈도, 서버 단일 처리 역량, 클러스터 규모에 기반한 서비스 체류시간 수학적 연산 체계.

## Ⅳ. 흐름도

<details><summary>핵심 용어(Core Terms)</summary>

- **대기열(Queue, 버퍼)**: 트래픽 대비 서버 가용 역량이 부족할 때, 처리 순번을 부여받고 메모리상에 임시 보관되는 논리적 완충 공간.
- **실측 보정(Empirical Calibration)**: 이론적 모형의 오차 유발 인자를 실제 환경 측정값과 대조해 튜닝하는 고도화 과정.
- **데이터 측정(Data Measurement)**: 시스템 로그 및 APM을 활용해 클라이언트 유입 간격 및 백엔드 트랜잭션 수행시간 데이터를 수집하는 작업.
- **모델 확정(Model Definition)**: 수집된 데이터 분석을 통해 확률 분포, 노드 수, 큐잉 방식을 켄달 표기법으로 모델링 선언하는 단계.
- **안정성 판별(Stability Check)**: 이용률($\rho$)이 1 미만인지 검증하여 무한 대기 폭주 모델을 차단하는 단계.
- **지표 산출(Metric Calculation)**: 대기열 평균 개수, 큐 대기시간, 트랜잭션 체류 지연시간을 수치화하는 단계.
- **실측 오차 반영(Error Correction)**: 이론적 결과치에 순간 부하 가중치 및 시스템 병목 오차를 반영하여 최종 용량을 산출하는 마무리 단계.

</details>

```text
측정 담당자
   │ 1. λ, μ, 분포 측정
   ▼
모형 선정자
   │ 2. 켄달 A/S/c/K/N/D 확정
   ▼
안정성 검증자
   │ 3. ρ = λ/(cμ) < 1 확인
   ▼
지표 산출자
   │ 4. L_q•W_q•W 계산
   ▼
보정 담당자
   │ 5. 실측 오차 반영
   ▼
용량 산정 결과
```

### 동작 원리

1. **λ, μ, 분포 측정**: 현행 운영 시스템의 APM과 로그 모니터링을 통한 **λ, μ, 분포 측정**을 실시하여 실효성 있는 기초 유입 패턴 및 성능 표본 데이터 수집.
2. **Kendall A/S/c/K/N/D 확정**: 측정된 데이터 양상에 가장 적합한 확률 분포를 부여하기 위해 **Kendall A/S/c/K/N/D 확정** 단계를 거쳐 이론 모형의 기반 조건 명문화.
3. **ρ = λ/(cμ) < 1 확인**: 적용된 모형이 발산(장애)하지 않도록 **ρ = λ/(cμ) < 1 확인**을 통해 필수적인 시스템 안정 한계 조건 충족 여부 최우선 검증.
4. **L_q•W_q•W 계산**: 대기열 혼잡 공식을 적용하는 **L_q•W_q•W 계산** 프로세스를 통해 사용자 체감 성능인 대기/체류시간 및 시스템 부하 지표 도출.
5. **실측 오차 반영**: 단순 수식 계산으로 커버되지 않는 비선형 트래픽 쏠림과 실제 **대기열** 적체 오차를 메우기 위해 **실측 보정** 기법인 **실측 오차 반영** 프로세스 수행.

#### 한줄 요약

- 실 트래픽 로그 기반 모델링 및 실측 데이터 보정을 통한 최적 서버 규모 확정 체계.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **M/M/1(Single Server Queue)**: 완전 무작위인 포아송 패턴으로 유입되는 트래픽을 단 하나의 서버 자원이 지수 분포 형태의 처리시간으로 감당하는 가장 기초적인 큐잉 모형.
- **M/M/c(Multi-Server Queue)**: 유입된 무작위 트래픽을 로드밸런싱 환경과 같이 동일한 성능을 띠는 $c$개의 복수 병렬 서버 풀이 분산 처리하는 고가용 대기행렬 모형.
- **DB(Database, 데이터베이스 계층)**: 동시성 트랜잭션 시 데이터 무결성을 위해 테이블이나 레코드 단위로 락(Lock)을 걸어 순차 처리 큐가 잦게 발생하는 크리티컬 백엔드 저장소.
- **WAS(Web Application Server, 애플리케이션 계층)**: 사용자 요청에 따라 세션 처리 및 비즈니스 동적 로직을 병렬 스레드를 활용해 스케일 아웃 형태로 다중 처리하는 미들웨어 서버.
- **적용 대상(Application Target)**: 순차 보장이 필수이거나 동시성 경합 제어가 강제되는 단일 장애점(DB 등)과 클러스터링 기반의 병렬 아키텍처(WAS 등)로 구분하여 모형을 채택하는 아키텍처적 판단 기준.
- **분배 불균형(Load Imbalance)**: 복수의 서버 노드가 투입되었음에도, 라우팅 알고리즘 한계나 세션 고착화 탓에 일부 노드에만 트래픽이 집중되어 전체 대기열 지연 효율이 급락하는 클러스터 혼잡 상태.

</details>

| 비교 항목 | M/M/1 단일 모형 | M/M/c 다중 병렬 모형 |
|:---|:---|:---|
| 아키텍처 **적용 대상** | 락 경합이 있는 **DB** 계층, 메시지 브로커의 단일 파티션 큐 | 클러스터링된 **WAS** 팜, 동시 응답 CS 상담원 풀 |
| 핵심 처리 특징 및 장점 | 직렬화된 **M/M/1** 단일 노드 순차 처리 구조로 무결성 담보 수월 | 로드밸런서 하단의 **M/M/c** 병렬 분산 처리로 전체 수용 용량 극대화 |
| 설계 시 한계 및 단점 | 트래픽 쏠림 시 즉각적 단일 서버 성능 포화 발생 및 SPOF 장애 위험 내포 | 트래픽 라우팅 실패 시 발생하는 극심한 **분배 불균형** 문제 및 공유 자원(DB 등) 병목 회피 불가 |

> 요약: 시스템 아키텍처의 물리적/논리적 토폴로지 특성에 부합하도록 단일 병목점 모델인 **M/M/1**과 수평 확장 모델인 **M/M/c**를 철저히 구분하여 용량 계획 적용.

#### 한줄 요약

- 단일 순차 처리(M/M/1)와 다중 병렬 처리(M/M/c) 모형의 효율 차이 입증 및 아키텍처 설계 반영.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어(Core Terms)</summary>

- **도착분포(Arrival Distribution)**: 유입 간격이 통계적으로 어떤 확률 형태인지 함수화한 모델.
- **서비스분포(Service Distribution)**: 단건 트랜잭션 처리시간의 흩어짐 양상을 정량화한 모델.

</details>

| 실무 한계 요인 | 현장 대응 전략 및 대책 | 기대 개선 효과 |
|:---|:---|:---|
| 시스템 가정 누락에 따른 이론-실제 지표 괴리 | 유입 트래픽의 **도착분포**, 인프라 **서비스분포** 및 Kendall 조건 모델링 공식 명시화 | 도출된 지표의 신뢰성, 재현성 및 기술적 논리성 확보 |
| 발산하는 큐 대기로 인한 분석 무의미화 | $\rho < 1$ **안정 조건** 준수 여부를 선행 검증하여 모형 투입 제한 | 큐가 무한정 팽창하여 시스템이 마비되는 불안정 아키텍처 설계 사전 배제 |
| 모형 통계 가정과 실무 시스템 실측 간 발생 편차 | 이론 큐잉 분석과 부하 테스트 기반 실측 및 시뮬레이션 모델링 기법의 하이브리드 병행 | 돌발 변수(가비지 컬렉션 딜레이, 네트워크 단절 등)에 의한 예측 오차 갭 감소 |

#### 한줄 요약

- 분산 서버 환경이 갖는 막대한 이론적 처리 용량 이점을 달성하기 위해 큐잉 시스템의 기본 전제 조건을 면밀히 분석하고 산정하는 능력 필수
