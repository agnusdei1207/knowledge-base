## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **대기행렬 이론**: 확률적 도착•서비스•대기 규칙으로 시스템의 혼잡과 지연을 분석하는 이론이다.
- **도착률($\lambda$)**: 단위 시간에 시스템으로 유입되는 평균 요청 수이다.
- **서비스율($\mu$)**: 서버 하나가 단위 시간에 처리할 수 있는 평균 요청 수이다.
- **대기 급증**: 도착률이 서비스 능력에 가까워질 때 작은 부하 증가에도 대기열과 지연이 비선형적으로 커지는 현상이다.

</details>

- 정의/개념: 확률적 도착•서비스로 **대기시간•필요 용량**을 예측하는 수리 이론이다.
- 배경/필요성: 평균 부하만으로는 **포화 직전 대기 급증 예측할 수 없다**.

#### 한줄 요약

- 손님 도착 속도와 창구 처리 속도로 줄 길이와 대기시간을 계산하는 것이 핵심이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **이용률($\rho$)**: 총 처리 능력 중 도착 부하가 차지하는 비율이다.
- **안정 조건**: 장기 도착률이 총 서비스 능력보다 낮아 대기열이 계속 증가하지 않는 조건이다.
- **가정 민감도**: 도착•서비스 분포, 대기열 용량, 처리 규칙의 차이에 따라 예측값이 크게 달라지는 성질이다.
- **얼랑 C(Erlang C)**: 병렬 서버가 모두 사용 중이어서 도착 요청이 기다릴 확률을 계산하는 공식이다.

</details>

- **혼잡 축**: 이용률이 포화에 접근하면 대기가 비선형 급증이다.
- **용량 축**: 안정 조건으로 처리 용량과 서버 수를 산정한다.
- **가정 축**: 분포•용량•규칙 변화에 예측값 민감이다.

#### 한줄 요약
- 처리 용량이 꽉 차기 직전에는 손님이 아주 조금만 더 와도 대기 줄이 걷잡을 수 없이 길어지는 성질이 있습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **Kendall 표기**: 도착분포•서비스분포•서버 수•수용량•모집단•대기 규칙을 나타내는 표기법이다.
- **M/M/1•M/M/c**: 도착률 $\lambda$의 포아송 도착, 서버당 서비스율 $\mu$의 지수 서비스, 서버 1개•$c$개를 가정한 모형이다.
- **대기시간($W_q$)**: 요청이 서비스 시작 전 대기열에 머문 평균 시간이다.
- **체류시간($W$)**: 요청이 시스템에 도착한 뒤 처리 완료까지 머문 평균 시간이다.
- **평균 작업 수($L$)**: 시스템 전체에 존재하는 평균 요청 수이다.
- **평균 대기열 길이($L_q$)**: 서비스 전 대기 중인 평균 요청 수이다.
- **FIFO(First In, First Out)**: 먼저 들어온 요청을 먼저 처리하는 규칙이다.
- **병렬 서버 수($c$)**: 동일 서비스율로 병렬 처리하는 서버 수이다.
- **대기 확률($P_{wait}$)**: 모든 서버가 사용 중이어서 기다릴 확률이다.

</details>

```text
대기행렬 모형
├─ 도착 과정
├─ 대기열
├─ 서비스 과정
├─ 대기 규칙
└─ Kendall 표기
```

가지의 의미: 확률적 도착•대기•서비스 조건을 Kendall 표기로 묶는 정적 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 도착 과정 | 도착분포와 **도착률 $\lambda$** 모델링 |
| 대기열 | 시스템 용량과 **차단 한계** 설정 |
| 서비스 과정 | 서비스분포•서버 수•**서비스율 $\mu$** 모델링 |
| 대기 규칙 | **FIFO•우선순위•포기** 규칙 정의 |
| Kendall 표기 | 분포•서버•용량•규칙의 **모형 조건** 명시 |

- **M/M/1**: $\rho=\lambda/\mu<1$, $W=1/(\mu-\lambda)$, $L=\lambda W$이다.
- **M/M/c**: $\rho=\lambda/(c\mu)<1$, $W_q=P_{wait}/(c\mu-\lambda)$이다.

#### 한줄 요약
- 들어오는 부하와 이를 처리하는 서버 수, 그리고 서버의 처리 능력에 따라 대기실에 머무는 대기 시간이 결정됩니다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **대기열**: 서버가 즉시 처리하지 못한 요청이 서비스 순서를 기다리는 공간이다.
- **실측 보정**: 폭주•의존성•분포 편차 때문에 생긴 모형 예측 오차를 실제 측정값으로 조정하는 과정이다.

</details>

```text
측정 담당자
   │ 1. λ, μ, 분포 측정
   ▼
모형 선정자
   │ 2. Kendall A/S/c/K/N/D 확정
   ▼
안정성 검증자
   │ 3. ρ = λ/(cμ) < 1 확인
   ▼
지표 산출자
   │ 4. L_q•W_q•W 계산
   ▼
보정 담당자
   │ 5. 실측 오차 반영
   ▼
용량 산정 결과
```

**동작 원리**

1. **λ, μ, 분포 측정**: 도착•서비스 표본을 수집한다.
2. **Kendall A/S/c/K/N/D 확정**: 분포•서버•용량•규칙을 명시한다.
3. **ρ = λ/(cμ) < 1 확인**: 안정 조건을 검증한다.
4. **L_q•W_q•W 계산**: 대기길이•체류시간을 산출한다.
5. **실측 오차 반영**: 폭주•의존성 편차를 보정한다.

#### 한줄 요약
- 유입 트래픽과 처리 시간을 측정하여 큐잉 모델 공식을 적용하고, 이를 토대로 필요한 서버의 개수를 판별합니다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **M/M/1**: 포아송 도착•지수 서비스•단일 서버를 가정한 대기행렬 모형이다.
- **M/M/c**: 포아송 도착•지수 서비스와 병렬 서버 $c$개를 가정한 모형이다.
- **DB(Database)**: 구조화 데이터를 저장•관리하는 데이터베이스이다.
- **WAS(Web Application Server)**: 웹 응용 로직을 실행하는 서버이다.
- **적용 대상**: 단일 서버는 DB•큐, 다중 서버는 WAS•상담 풀에 적용한다.
- **분배 불균형**: 병렬 서버가 있어도 일부 서버에 요청이 몰려 전체 대기가 늘어나는 상태이다.

</details>

| 대기행렬 모형 | M/M/1 | M/M/c |
|:---|:---|:---|
| 적용 기준 | 단일 **DB•큐 병목** 분석 | **WAS•상담 풀** 용량 산정 |
| 핵심 특징 | **서버 1개** 순차 처리 | **서버 $c$개** 병렬 처리 |
| 한계 | **단일 서버 장애•포화** | **분배 불균형•공유 병목** |

> 요약: 단일 서버 **M/M/1**과 다중 서버 **M/M/c**을 비교한다.

#### 한줄 요약
- 단일 창구에서 차례를 기다리는 방식과 여러 창구가 하나의 대기선으로 연결된 방식의 효율성 차이를 분석합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **도착분포**: 요청 간 도착시간이 어떤 확률 형태로 나타나는지를 설명하는 분포이다.
- **서비스분포**: 요청별 처리시간이 어떤 확률 형태로 나타나는지를 설명하는 분포이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 분포•용량을 생략해 결과가 달라지는 **가정 누락** | **Kendall A/S/c/K/N/D**를 명시 | 모형의 **해석•재현성** 확보 |
| 포화 모형을 정상 상태로 해석하는 **적용 오류** | **$\lambda<c\mu$ 안정 조건** 검증 | **불안정 용량 설계** 배제 |
| 독립•지수 가정과 실측이 다른 **분포 편차** | **실측•시뮬레이션**을 병행 | 용량의 **예측 오차** 감소 |

#### 한줄 요약
- 연결 여러 개가 함께 처리하는 요청 수와 기다리는 시간을 계산합니다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **포화 직전 비선형 증가**: 이용률이 1에 가까워질수록 작은 부하 증가가 대기시간을 크게 늘리는 현상이다.
- **용량 산정**: 목표 도착률과 지연을 만족하도록 서버 수와 서비스율을 결정하는 작업이다.
- **모형 선택**: 단일 서버는 M/M/1, 병렬 서버 풀은 M/M/c를 적용하고 안정 조건을 만족하는 서버 수를 정하는 결정이다.

</details>

- 단일 서버는 **M/M/1**, 병렬 풀은 **M/M/c**로 안정 서버 수를 결정한다.

#### 한줄 요약
- 손님이 오는 속도보다 처리 속도가 충분히 빠르도록 창구 수를 정합니다.
