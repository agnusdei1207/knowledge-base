## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **큐잉 이론(Queuing Theory / 대기행렬 이론)**: 무작위(Random)로 유입되는 서비스 요청의 도착률(Arrival Rate, $\lambda$)과 서버의 처리 서비스율(Service Rate, $\mu$)을 확률 과정(Poisson/Exponential Distribution)으로 수학적 모델링하여, 시스템 내 대기열 길이($L_q$)와 평균 체류 시간($W$)을 정량적으로 산출하고 최적의 서버 용량을 산정하는 수리 성능 분석 기법.
- **자원 이용률 100% 접근에 따른 비선형 대기열 폭증 결함(Non-linear Hockey-Stick Latency Defect)**: 서버의 CPU 이용률($\rho$)이 80%~90%를 초과할 때, 대기시간($W_q$)이 선형적으로 증가하는 것이 아니라 분모의 $(1-\rho)$ 수식에 의해 지수적/비선형적으로 폭증(하키스틱 곡선)하여 시스템이 순식간에 응답 불가(Hang) 상태에 빠지는 수학적 결함.

</details>

- 정의/개념: 도착률과 서비스율의 확률 분포로 대기열($L_q$)·체류시간($W$)을 산출해 목표 SLA를 만족하는 최소 서버 수($c$)를 정하는 **큐잉 이론** 기반 수리적 용량 사이징 체계
- 배경/필요성: 트래픽 유입 시 서버 이용률($\rho$)이 80%~90%를 초과할 때 대기시간($W_q$)이 선형이 아닌 $(1-\rho)$ 분모 수식에 의해 지수적·비선형적으로 폭증(하키스틱 곡선)하는 대기행렬 특성을 고려하지 않고 주관적 경험에 의존하여 인프라를 증설할 경우, 버스트 부하 발생 시 시스템 행(Hang) 및 연쇄 타임아웃 붕괴를 초래하거나 과도한 오버프로비저닝으로 비용이 낭비되는 구조적 결함이 발생함에 따라, 켄달 표기법($A/S/c/K/N/D$)과 M/M/1 및 M/M/c 수리 모델에 기반하여 도착률($\lambda$)과 서비스율($\mu$)의 확률 분포를 분석하고 안정 조건($\rho < 1$) 및 체류시간($W$)을 정량 계산하는 큐잉 이론 체계를 도입하여 비선형 대기 폭증 임계점 사전 방어, 목표 SLA 충족을 위한 최소 병렬 서버 수($c$) 과학적 산정 및 최적의 인프라 ROI 확보를 달성할 필요

#### 한줄 요약
- 증설 한 대의 비용은 선형이지만 대기시간은 $(1-\rho)$ 분모로 비선형이므로, 이용률 80% 부근의 마지막 몇 %를 비우는 데 쓰는 서버가 가장 싼 지연 보험이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- 큐잉 이론 3대 핵심 모델링 변수:
  - **도착률 ($\lambda$, Arrival Rate)**: 단위 시간당 시스템으로 유입되는 평균 요청 건수 (Poisson 과정).
  - **서비스율 ($\mu$, Service Rate)**: 단일 서버가 단위 시간당 완전히 처리할 수 있는 평균 요청 건수 (Exponential 분포).
  - **서버 이용률 ($\rho$, Traffic Intensity / Utilization)**: 단일 서버 모델에서 $\rho = \frac{\lambda}{\mu}$, $c$개 서버 모델에서 $\rho = \frac{\lambda}{c\mu}$.
- **얼랑 C 공식(Erlang-C Formula)**: M/M/c 모델에서 도착한 요청이 모든 서버가 사용 중이어서 대기해야 할 확률을 $\lambda$·$\mu$·$c$로 구하는 식으로, 이 대기 확률에 평균 대기시간을 곱해 공용 큐의 기대 지연을 산출한다.

</details>

- **도착률**이 **서비스율**과 서버 수의 곱에 가까워질수록 발산하는 비선형 대기시간
- **서버 이용률** $\rho<1$ 인 안정 조건에서만 정상 상태 해가 존재
- 공용 큐의 대기 확률을 구하는 **Erlang-C**

#### 한줄 요약
- 세 변수 중 설계자가 통제할 수 있는 것은 $c$뿐이라, 도착률 예측 오차는 결국 서버 수의 여유로 흡수해야 하며 그 여유가 곧 비용이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- 켄달 표기법 (Kendall's Notation: $A / S / c / K / N / D$):
  - $A$: 도착 시간 간격 분포 ($M$: Markovian/Poisson, $D$: Deterministic, $G$: General).
  - $S$: 서비스 시간 분포 ($M$: Exponential, $D$: Deterministic, $G$: General).
  - $c$: 병렬 서비스 처리 서버 대수 ($1, 2, \dots, \infty$).
  - $K$: 시스템 최대 수용 용량 (생략 시 $\infty$).
  - $N$: 소스 모집단 크기 (생략 시 $\infty$).
  - $D$: 대기열 처리 규칙 (FIFO, LIFO, Priority, 생략 시 FIFO).

</details>

```text
켄달 표기법 A/S/c/K/N/D
├─ A·S
│  └─ 도착·서비스 시간 분포
├─ c·K
│  └─ 서버 수·시스템 수용량
└─ N·D
   └─ 모집단 크기·대기 규칙
```

선의 의미: 포아송 유입 요청이 대기열을 거쳐 $c$개의 병렬 서버에서 처리되는 흐름과 M/M/1 및 M/M/c 수식 체계

| 구성요소 | 책임 |
|:---|:---|
| A | 도착 시간 간격 분포 정의 |
| S | 서비스 시간 분포 정의 |
| c | 병렬 서버 수 정의 |
| K | 시스템 최대 수용량 정의 |
| N | 요청 소스 모집단 크기 정의 |
| D | FIFO·LIFO·Priority 대기 규칙 정의 |

#### 한줄 요약
- 켄달 표기법은 여섯 자리로 대기 시스템을 기술하되 $K$·$N$을 생략하면 무한 수용과 무한 모집단을 가정하므로, 실제로는 거절되거나 재시도되는 요청까지 대기열에 남아 있는 것으로 계산돼 산정치가 낙관적으로 어긋난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- 큐잉 이론 기반 용량 사이징 5단계 계산 프로세스:
  1. 목표 워크로드의 평균 도착률($\lambda$) 및 단일 서버 처리율($\mu$) 실측
  2. 시스템 아키텍처에 적합한 켄달 표기법 모델(M/M/1 vs M/M/c) 선정
  3. 안정 조건($\rho = \frac{\lambda}{c\mu} < 1$) 충족 여부 1차 검증
  4. M/M/c 수식을 통해 목표 응답시간($W \le W_{target}$)을 만족하는 최소 서버 대수($c$) 산출
  5. 부하 테스트(JMeter)를 통해 이론 계산치와 실측치 오차를 대조하고 안전 여유(Headroom) 반영

</details>

```text
1. [유입률 및 처리율 실측]
    ├─ 피크 시간대 결제 요청 도착률: $\lambda = 1,000 \text{ req/sec}$
    └─ [단일 WAS 인스턴스의 평균 처리 속도: $\mu = 150 \text{ req/sec}$ (건당 평균 6.67ms 소요)]
            │
            ▼
2. [큐잉 모델 및 목표 SLA 설정]
    ├─ 로드밸런서 기반 공용 큐 분배 구조 ➔ M/M/c 모델 채택
    └─ [목표 서비스 수준: 평균 응답시간 $W \le 20\text{ms}$ (0.02초) 보증]
            │
            ▼
3. [최소 서버 대수 (안정 조건) 1차 판정]
    ├─ $\rho = \frac{\lambda}{c\mu} < 1 \implies c > \frac{\lambda}{\mu} = \frac{1000}{150} \approx 6.67$
    └─ [최소 7대 이상이어야 대기열이 무한 발산하지 않고 시스템이 안정됨]
            │
            ▼
4. [M/M/c 수식 기반 목표 응답시간 계산]
    ├─ $c = 7$대 시: $\rho = \frac{1000}{1050} = 0.952$ (95.2%) ➔ $W = 65\text{ms}$ (목표 20ms 미달)
    ├─ $c = 8$대 시: $\rho = \frac{1000}{1200} = 0.833$ (83.3%) ➔ $W = 12.5\text{ms}$ (목표 20ms 만족)
    └─ [이론상 최소 8대의 WAS 인스턴스가 필요함을 수학적으로 확정]
            │
            ▼
5. [안전 여유(Headroom) 반영 및 실측 보정]
    ├─ 버스트 트래픽(Poisson 가정 오차) 및 페일오버(N+1) 고려하여 $+20\%$ 여유 적용
    └─ [최종 확정: 총 10대의 WAS 인스턴스 프로비저닝 (피크 시 가동률 66.7%, $W \approx 7.8\text{ms}$ 유지)]
```

분기 결과: 안정 조건($c>6.67$)은 7대에서 통과하지만 목표 응답시간 $W\le20$ms는 8대부터 만족하므로 판정은 4단계에서 갈리고, 여기에 버스트·N+1 여유 20%를 더한 10대가 최종 프로비저닝 수가 된다.

#### 한줄 요약
- 안정 조건만 겨우 만족하는 7대는 가동률 95.2%에서 $W$가 65ms로 치솟고 한 대를 더한 8대는 12.5ms로 내려가므로, 갈래는 서버 대수 자체가 아니라 포화 직전 구간의 대기시간 급증에서 갈린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- 큐잉 아키텍처 3대 토폴로지 비교:
  - 단일 큐-단일 서버 (M/M/1): 직렬 처리 구조.
  - 단일 큐-다중 서버 (M/M/c): 글로벌 로드밸런싱 풀 구조.
  - 다중 큐-다중 서버 ($c \times M/M/1$): 파티셔닝/샤딩 분할 구조.

</details>

| 비교 항목 | M/M/1 (단일 큐 - 단일 서버) | M/M/c (단일 큐 - 다중 병렬 서버) | $c \times$ M/M/1 (개별 큐 - 개별 서버) |
|:---|:---|:---|:---|
| 큐 구조 | 1개 큐 $\rightarrow$ 1대 서버 | 1개 공용 큐 $\rightarrow$ $c$대 병렬 서버 | **$c$개 개별 큐 $\rightarrow$ $c$대 개별 서버** |
| 적용 사례 | Node.js 단일 스레드, DB Mutex | WAS 로드밸런서, 쿠버네티스 서비스| Kafka 파티션별 컨슈머, 샤딩 DB |
| 대기 시간 ($W_q$)| 가장 김 ($W_q = \frac{\rho}{\mu(1-\rho)}$)| 가장 짧음 (얼랑 C 분산 효과) | 중간 (큐 간 부하 불균형 시 지연)|
| 서버 유휴 낭비 | 없음 (단일 자원) | 최소화 (놀고 있는 서버가 즉시 처리)| 큼 (특정 큐는 꽉 차고 타 큐는 놂)|
| 장애 영향도 (SPOF)| 치명적 (서버 다운 시 서비스 마비) | 격리 (1대 장애 시 $c-1$대로 가동) | 부분적 (해당 파티션만 서비스 중단)|

#### 한줄 요약
- 공용 큐는 대기시간과 유휴를 동시에 최소화하지만 큐 자체가 단일 지점이 되고, 개별 큐는 격리를 얻는 대신 큐 간 불균형 지연을 치르므로, 격리가 필요한 데이터 파티션이 아니면 공용 큐가 기본값이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **폴라첵-킨친 공식(Pollaczek-Khinchine Formula)**: 도착은 포아송이지만 서비스 시간이 일반 분포인 M/G/1 큐의 평균 대기시간을 $W_q = \frac{\lambda(\sigma^2 + 1/\mu^2)}{2(1-\rho)}$로 구하는 식으로, 서비스 시간 분산 $\sigma^2$이 커질수록 같은 이용률에서도 대기가 길어짐을 정량화한다.
- **HPA(Horizontal Pod Autoscaler)**: 쿠버네티스에서 CPU 이용률 등 메트릭이 목표치를 넘으면 파드 복제 수를 자동으로 늘리고 내려가면 줄이는 컨트롤러로, 큐잉 모델의 서버 수 $c$를 부하에 따라 동적으로 조절한다.
- **최소 연결(Least Connections)**: 로드밸런서가 현재 활성 연결 수가 가장 적은 서버로 새 요청을 보내는 분배 알고리즘으로, 라운드로빈과 달리 처리가 느린 노드에 요청이 적체되는 것을 자동으로 완화한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 롱테일(Pareto) 서비스 시간에서 M/M/1 예측치 대비 실제 대기시간 폭증 | **폴라첵-킨친 공식**으로 서비스 시간 분산($\sigma^2$) 반영 | 비정규 트래픽에서 대기시간 예측 오차 축소 |
| 가동률 90% 이상 운영 시 버스트에 하키스틱 지연·연쇄 타임아웃 | 목표 이용률 70~75% 상한과 **HPA** 임계치 연동 | 비선형 대기 폭증 구간 진입 차단 |
| 느린 노드로 라우팅된 요청 적체로 클러스터 불균형 | 라운드로빈 대신 **최소 연결** 동적 분배 | 노드 간 처리 편차 제거 |

#### 한줄 요약
- 세 대책은 모두 모델 가정(지수 분포·평균 이용률·균등 분배)이 깨지는 지점을 실측으로 메우는 것이므로, 수식 결과는 상한이 아니라 하한으로 읽어야 한다.

## Ⅶ. 결론

- 불확실한 트래픽 환경에서 대기열 지연과 서버 처리 역학을 수학적 확률 모델로 규명하여 인프라 증설의 수리적 타당성을 제공하는 대기행렬 기반 시스템 용량 산정 및 성능 모델링(Queuing Theory / M/M/1 & M/M/c / Erlang-C)의 핵심 이론 표준으로 확고히 자리 잡았으며, 클라우드 오토스케일링(HPA) 정책 알고리즘 및 마이크로서비스 메시 큐(Kafka/RabbitMQ) 버퍼 사이징으로 확장되는 가운데, 실무 인프라 용량 사이징 시에는 롱테일 트래픽 보정을 위한 M/G/1 Pollaczek-Khinchine 공식 적용, 비선형 대기 폭증 방지를 위한 평상시 목표 가동률 70% 이하 제한, 개별 큐 분할 대비 대기 지연을 최소화하는 공용 큐 기반 M/M/c 로드밸런싱 풀 구성을 결합하여 완벽한 대기행렬 복원력을 완성

#### 한줄 요약
- 서버 수 산정의 기준은 안정 조건 통과가 아니라 목표 응답시간과 여유율이며, 가동률 70% 상한은 낭비가 아니라 비선형 구간을 피하는 보험료다.
