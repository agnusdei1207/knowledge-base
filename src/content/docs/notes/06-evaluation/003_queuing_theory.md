## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **큐잉 이론(Queuing Theory / 대기행렬 이론)**: 무작위(Random)로 유입되는 서비스 요청의 도착률(Arrival Rate, $\lambda$)과 서버의 처리 서비스율(Service Rate, $\mu$)을 확률 과정(Poisson/Exponential Distribution)으로 수학적 모델링하여, 시스템 내 대기열 길이($L_q$)와 평균 체류 시간($W$)을 정량적으로 산출하고 최적의 서버 용량을 산정하는 수리 성능 분석 기법.
- **자원 이용률 100% 접근에 따른 비선형 대기열 폭증 결함(Non-linear Hockey-Stick Latency Defect)**: 서버의 CPU 이용률($\rho$)이 80%~90%를 초과할 때, 대기시간($W_q$)이 선형적으로 증가하는 것이 아니라 분모의 $(1-\rho)$ 수식에 의해 지수적/비선형적으로 폭증(하키스틱 곡선)하여 시스템이 순식간에 응답 불가(Hang) 상태에 빠지는 수학적 결함.

</details>

- 정의/개념: 인프라 증설 비용과 사용자 대기시간 간의 최적 균형을 수리적으로 도출하기 위해 **켄달 표기법($A/S/c/K/N/D$) 모델링 $\rightarrow$ 포아송 도착 및 지수 서비스 시간 가정 $\rightarrow$ 시스템 안정 조건($\rho = \frac{\lambda}{c\mu} < 1$) 검증 $\rightarrow$ M/M/1 및 M/M/c 수식 기반 체류 지연($W$) 및 대기열($L_q$) 산출 $\rightarrow$ 목표 SLA 충족 최소 서버 수($c$) 산정** 을 집행하는 **수리적 성능 용량 사이징 체계**
- 배경/필요성: 무조건적인 하드웨어 과다 증설(Over-provisioning)을 방지하고 피크 트래픽 유입 시 목표 응답시간을 보증할 수 있는 객관적인 수리 모델 필요

#### 한줄 요약
- 큐잉 이론은 유입률과 서비스율의 확률 분포를 기반으로 대기열 길이와 체류시간을 수학적으로 계산하여 최적 서버 용량을 산출한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **큐잉 이론 3대 핵심 모델링 변수**:
  - **도착률 ($\lambda$, Arrival Rate)**: 단위 시간당 시스템으로 유입되는 평균 요청 건수 (Poisson 과정).
  - **서비스율 ($\mu$, Service Rate)**: 단일 서버가 단위 시간당 완전히 처리할 수 있는 평균 요청 건수 (Exponential 분포).
  - **서버 이용률 ($\rho$, Traffic Intensity / Utilization)**: 단일 서버 모델에서 $\rho = \frac{\lambda}{\mu}$, $c$개 서버 모델에서 $\rho = \frac{\lambda}{c\mu}$.

</details>

- **비선형 지연 특성의 수학적 규명**: 대기시간 수식($W = \frac{1}{\mu - \lambda}$)을 통해 이용률 $\rho \to 1.0$ 접근 시 대기시간이 무한대로 발산함을 증명
- **시스템 안정 조건(Stability Condition)의 절대성**: 유입률이 총 서비스 용량을 초과하면($\lambda \ge c\mu, \rho \ge 1.0$) 큐가 영구히 발산하여 시스템이 붕괴하므로 반드시 $\rho < 1.0$ 유지 강제
- **단일 대기열 vs 다중 대기열의 효율성 비교**: 1개의 공용 큐에서 $c$대의 서버로 작업을 분배하는 M/M/c 모델이 $c$개의 개별 M/M/1 큐를 운용하는 것보다 평균 대기시간이 대폭 단축됨을 얼랑 C(Erlang-C) 공식으로 입증

#### 한줄 요약
- 비선형 대기 폭증 규명, 시스템 안정 조건($\rho < 1$) 검증, M/M/c 단일 공용 큐의 효율성 증명을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **켄달 표기법 (Kendall's Notation: $A / S / c / K / N / D$)**:
  - $A$: 도착 시간 간격 분포 ($M$: Markovian/Poisson, $D$: Deterministic, $G$: General).
  - $S$: 서비스 시간 분포 ($M$: Exponential, $D$: Deterministic, $G$: General).
  - $c$: 병렬 서비스 처리 서버 대수 ($1, 2, \dots, \infty$).
  - $K$: 시스템 최대 수용 용량 (생략 시 $\infty$).
  - $N$: 소스 모집단 크기 (생략 시 $\infty$).
  - $D$: 대기열 처리 규칙 (FIFO, LIFO, Priority, 생략 시 FIFO).

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 켄달 표기법 기반 대기행렬 시스템 구조 (Kendall's Queue Structure) ]│
│                                                                         │
│  도착 과정 (A: λ)           대기열 (Queue: K)           서비스 서버 (S: μ)│
│  ───────────────► ┌───────────────────────────┐ ──► [ Server 1: μ ]     │
│   (Poisson 유입)  │ [요청] [요청] [요청] ...   │ ──► [ Server 2: μ ]     │
│                   └───────────────────────────┘ ──► [ Server c: μ ]     │
│                         대기 규칙 (D: FIFO)           (c개 병렬 서버)   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (확률 수식 전개)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. M/M/1 단일 서버 큐잉 모델 수식 체계 (Single Server Queue) ]        │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 이용률 (Utilization) ]          │ $\rho = \frac{\lambda}{\mu}$        │
│ [ 평균 시스템 내 요청 수 (L) ]    │ $L = \frac{\rho}{1 - \rho} = \frac{\lambda}{\mu - \lambda}$ │
│ [ 평균 대기열 내 요청 수 (L_q) ]  │ $L_q = L - \rho = \frac{\rho^2}{1 - \rho} = \frac{\lambda^2}{\mu(\mu - \lambda)}$ │
│ [ 평균 시스템 체류 시간 (W) ]     │ $W = \frac{L}{\lambda} = \frac{1}{\mu - \lambda} = \frac{1}{\mu(1 - \rho)}$ │
│ [ 평균 큐 대기 시간 (W_q) ]       │ $W_q = W - \frac{1}{\mu} = \frac{\rho}{\mu(1 - \rho)} = \frac{\lambda}{\mu(\mu - \lambda)}$ │
└───────────────────────────────────┴─────────────────────────────────────┘
                                     │ (다중 서버 확장)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. M/M/c 다중 서버 큐잉 모델 및 얼랑 C 수식 (Multi-Server Queue) ]    │
│  ├─ [ 트래픽 강도 (Traffic Intensity) ] ➔ $a = \frac{\lambda}{\mu}$, 이용률 $\rho = \frac{a}{c} = \frac{\lambda}{c\mu} < 1$ │
│  ├─ [ 얼랑 C 대기 확률 (Erlang-C) ] ➔ $C(c, a) = P(\text{Wait} > 0) = \frac{\frac{a^c}{c!(1-\rho)}}{\sum_{k=0}^{c-1}\frac{a^k}{k!} + \frac{a^c}{c!(1-\rho)}}$ │
│  └─ [ M/M/c 평균 큐 대기 시간 (W_q) ] ➔ $W_q = \frac{C(c, a)}{c\mu - \lambda} = \frac{C(c, a)}{c\mu(1-\rho)}$ │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 포아송 유입 요청이 대기열을 거쳐 $c$개의 병렬 서버에서 처리되는 흐름과 M/M/1 및 M/M/c 수식 체계

| 모델 구분 | 켄달 표기 | 핵심 적용 환경 | 평균 체류 시간 ($W$) 수식 | 비고 |
|:---|:---|:---|:---|:---|
| **M/M/1** | $M/M/1/\infty/\infty/FIFO$ | 단일 스레드 이벤트 루프, DB Row Lock, 단일 CPU 코어 | $W = \frac{1}{\mu - \lambda}$ | 순차 직렬 처리 |
| **M/M/c** | $M/M/c/\infty/\infty/FIFO$ | 웹/WAS 로드밸런싱 클러스터, 스레드 풀, DB 커넥션 풀 | $W = W_q + \frac{1}{\mu} = \frac{C(c,a)}{c\mu - \lambda} + \frac{1}{\mu}$ | 병렬 수평 분산 |
| **M/D/1** | $M/D/1/\infty/\infty/FIFO$ | 처리 시간이 일정한 하드웨어 DMA 전송, 패킷 고정 라우팅 | $W = \frac{1}{\mu} + \frac{\rho}{2\mu(1-\rho)}$ (Pollaczek-Khinchine) | 지연 분산 최소화 |
| **M/M/c/K**| $M/M/c/K/\infty/FIFO$ | 백로그 큐 크기가 제한된 소켓 버퍼, 패킷 드롭 라우터 | $P_{loss}$ (큐 오버플로우 차단 확률 계산) | 유한 큐 모델 |

#### 한줄 요약
- 켄달 표기법, M/M/1 단일 수식 체계, M/M/c 얼랑 C 다중 수식 체계, M/D/1 모델로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **큐잉 이론 기반 용량 사이징 5단계 계산 프로세스**:
  1. 목표 워크로드의 평균 도착률($\lambda$) 및 단일 서버 처리율($\mu$) 실측
  2. 시스템 아키텍처에 적합한 켄달 표기법 모델(M/M/1 vs M/M/c) 선정
  3. 안정 조건($\rho = \frac{\lambda}{c\mu} < 1$) 충족 여부 1차 검증
  4. M/M/c 수식을 통해 목표 응답시간($W \le W_{target}$)을 만족하는 최소 서버 대수($c$) 산출
  5. 부하 테스트(JMeter)를 통해 이론 계산치와 실측치 오차를 대조하고 안전 여유(Headroom) 반영

</details>

```text
1. [유입률 및 처리율 실측]
    ├─ 피크 시간대 결제 요청 도착률: $\lambda = 1,000 \text{ req/sec}$
    └─ [단일 WAS 인스턴스의 평균 처리 속도: $\mu = 150 \text{ req/sec}$ (건당 평균 6.67ms 소요)]
            │
            ▼
2. [큐잉 모델 및 목표 SLA 설정]
    ├─ 로드밸런서 기반 공용 큐 분배 구조 ➔ M/M/c 모델 채택
    └─ [목표 서비스 수준: 평균 응답시간 $W \le 20\text{ms}$ (0.02초) 보증]
            │
            ▼
3. [최소 서버 대수 (안정 조건) 1차 판정]
    ├─ $\rho = \frac{\lambda}{c\mu} < 1 \implies c > \frac{\lambda}{\mu} = \frac{1000}{150} \approx 6.67$
    └─ [최소 7대 이상이어야 대기열이 무한 발산하지 않고 시스템이 안정됨]
            │
            ▼
4. [M/M/c 수식 기반 목표 응답시간 계산]
    ├─ $c = 7$대 시: $\rho = \frac{1000}{1050} = 0.952$ (95.2%) ➔ $W = 65\text{ms}$ (목표 20ms 미달)
    ├─ $c = 8$대 시: $\rho = \frac{1000}{1200} = 0.833$ (83.3%) ➔ $W = 12.5\text{ms}$ (목표 20ms 만족)
    └─ [이론상 최소 8대의 WAS 인스턴스가 필요함을 수학적으로 확정]
            │
            ▼
5. [안전 여유(Headroom) 반영 및 실측 보정]
    ├─ 버스트 트래픽(Poisson 가정 오차) 및 페일오버(N+1) 고려하여 $+20\%$ 여유 적용
    └─ [최종 확정: 총 10대의 WAS 인스턴스 프로비저닝 (피크 시 가동률 66.7%, $W \approx 7.8\text{ms}$ 유지)]
```

**동작 원리**

1. **포아송 과정의 무기억성(Memoryless Property)**: 과거의 도착 이력이 미래의 도착 확률에 영향을 주지 않는 $P(X > s+t \mid X > s) = P(X > t)$ 특성을 기반으로 수학적 해석 단순화
2. **리틀의 법칙 연계**: 시스템 내 평균 체류 작업 수($L$)와 큐 대기 작업 수($L_q$)는 $L = \lambda W$, $L_q = \lambda W_q$의 관계를 엄격히 만족
3. **얼랑 C 대기 확률**: 트래픽 강도($a = \frac{\lambda}{\mu}$)가 증가할 때 모든 $c$개 서버가 바빠서 신규 요청이 대기열로 들어갈 확률($C(c, a)$)을 정확히 계산
4. **규모의 경제(Economy of Scale)**: 1개의 거대한 단일 풀(M/M/c)이 여러 개의 쪼개진 소규모 풀($c \times M/M/1$)보다 버스트 흡수력과 대기시간 감소율이 월등히 우수함
5. **선제적 용량 예측**: 실제 인프라를 구축하기 전에 트래픽 증가($\lambda$)에 따른 필요 서버 수($c$)를 수학적으로 사전 산정 가능

#### 한줄 요약
- $\lambda$와 $\mu$ 실측, M/M/c 모델 선정, 안정 조건 검증, 목표 $W$ 만족 최소 $c$ 계산, 안전 여유 반영 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **큐잉 아키텍처 3대 토폴로지 비교**:
  - 단일 큐-단일 서버 (M/M/1): 직렬 처리 구조.
  - 단일 큐-다중 서버 (M/M/c): 글로벌 로드밸런싱 풀 구조.
  - 다중 큐-다중 서버 ($c \times M/M/1$): 파티셔닝/샤딩 분할 구조.

</details>

| 비교 항목 | M/M/1 (단일 큐 - 단일 서버) | M/M/c (단일 큐 - 다중 병렬 서버) | $c \times$ M/M/1 (개별 큐 - 개별 서버) |
|:---|:---|:---|:---|
| **큐 구조** | **1개 큐 $\rightarrow$ 1대 서버** | **1개 공용 큐 $\rightarrow$ $c$대 병렬 서버** | **$c$개 개별 큐 $\rightarrow$ $c$대 개별 서버** |
| **적용 사례** | Node.js 단일 스레드, DB Mutex | **WAS 로드밸런서, 쿠버네티스 서비스**| **Kafka 파티션별 컨슈머, 샤딩 DB** |
| **대기 시간 ($W_q$)**| 가장 김 ($W_q = \frac{\rho}{\mu(1-\rho)}$)| **가장 짧음 (얼랑 C 분산 효과)** | 중간 (큐 간 부하 불균형 시 지연)|
| **서버 유휴 낭비** | 없음 (단일 자원) | **최소화 (놀고 있는 서버가 즉시 처리)**| 큼 (특정 큐는 꽉 차고 타 큐는 놂)|
| **장애 영향도 (SPOF)**| 치명적 (서버 다운 시 서비스 마비) | **격리 (1대 장애 시 $c-1$대로 가동)** | 부분적 (해당 파티션만 서비스 중단)|

#### 한줄 요약
- M/M/1은 직렬 순차 처리, M/M/c는 공유 큐 기반 최고 효율성, 개별 M/M/1은 파티션 격리에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **큐잉 이론 실무 적용 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 실제 트래픽이 지수 분포(Exponential)가 아닌 극단적 롱테일(Pareto/Log-Normal) 형태여서 **M/M/1 공식 예측치보다 실제 운영 대기시간이 10배 이상 폭증** | **일반 분포를 지원하는 M/G/1 Pollaczek-Khinchine 공식($W_q = \frac{\lambda(\sigma^2 + 1/\mu^2)}{2(1-\rho)}$)을 적용하고 서비스 시간 분산($\sigma^2$) 튜닝** | 비정규 트래픽 환경에서도 대기시간 예측 정확도 95% 확보 |
| 서버 가동률을 90% 이상으로 유지하여 비용을 아끼려다 **순간 버스트 트래픽 유입 시 하키스틱 지연 급증 및 연쇄 타임아웃 붕괴(Cascading Failure) 발생** | **목표 이용률($\rho$)을 최대 70%~75% 이하로 제한하고, HPA(Horizontal Pod Autoscaler) 임계치를 CPU 70%에 연동** | 버스트 유입 시에도 비선형 대기 폭증 원천 차단 |
| M/M/c 로드밸런싱 환경에서 특정 WAS 노드의 Slow-query로 인해 **해당 노드로 라우팅된 요청들이 적체되며 전체 클러스터 성능이 저하되는 불균형 발생** | **단순 라운드로빈(RR) 대신 Least Connections 및 응답시간 가중치 기반 동적 로드밸런싱 알고리즘 강제** | 노드 간 처리 편차 제거 및 클러스터 전체 처리율 극대화 |

#### 한줄 요약
- M/G/1으로 롱테일을 보정하고, 가동률 70% 제한으로 대기 폭증을 막으며, 최소 연결 라우팅으로 불균형을 해소한다.

## Ⅶ. 결론

- 시스템의 불확실한 트래픽 유입을 수학적으로 제어하고 최적의 서버 규모를 산정하는 성능 공학의 기초 이론인 **큐잉 이론 체계**는 단순한 경험적 추정을 배제하고 수학적 정량성에 기반하여 SLA를 보증하는 핵심 도구이며, 실무 구현 시 **켄달 표기법 기반의 정확한 시스템 모델링**, **안정 조건($\rho < 1$) 및 가동률 70% 이내 통제**, **단일 공용 큐(M/M/c) 기반의 병렬 로드밸런싱 아키텍처 확립**, **실측 분산($\sigma^2$)을 반영한 M/G/1 보정**을 완성하여 최고 수준의 비용 효율성과 예측 가능한 응답 성능을 완성

#### 한줄 요약
- 켄달 표기법과 M/M/c 수식 체계를 통해 비선형 대기 폭증을 방어하고 최적의 서버 용량을 산정한다.
