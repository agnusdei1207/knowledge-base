## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **정보시스템 감리 유형(Information System Audit Types / 행정안전부 고시)**: 정보화 사업의 총사업비 규모, 기술적 난이도, 위험도, 사업 수행 방식에 따라 감리원의 투입 시점, 기간, 점검 범위를 전략적으로 최적화하여, 요구정의$\cdot$설계$\cdot$종료 단계별 관문(Gate)을 통제하는 **단계감리(3단계/2단계)**, 전 기간 상주하며 상시 위험을 모니터링하는 **상주감리(Resident Audit)**, 중대 장애나 분쟁 등 특정 현안을 집중 진단하는 **특정감리(Specific Audit)** 등으로 분류한 체계.
- **단계 간 공백 위험 누적 및 상주감리의 독립성 오염 결함(Audit Gap & Self-Audit Defect)**: 마일스톤별 정기 감리만 수행하여 단계 사이에 발생한 아키텍처 변질과 데이터 모델 붕괴를 뒤늦게 발견하거나, 상주감리원이 프로젝트 의사결정 및 개발 자문에 직접 개입하여 본인이 자문한 내용을 스스로 감사하는 '셀프 감사(Self-Audit)'로 독립성이 상실되는 구조적 결함.

</details>

- 정의/개념: 프로젝트 위험 특성에 따라 최적의 품질 보증 효과를 달성하기 위해 **사업 위험도 및 법정 의무 기준 평가 $\rightarrow$ 단계감리(3단계/2단계) $\cdot$ 상주감리 $\cdot$ 특정감리 유형 최적 조합 $\rightarrow$ 분야별 전문 감리원(DB/보안/클라우드) 투입 $\rightarrow$ 공통 식별자 기반 차수별 지적사항 추적 $\rightarrow$ 시정조치 완결 및 프로젝트 안전 착륙** 을 집행하는 **맞춤형 IT 감리 거버넌스 체계**
- 배경/필요성: 획일적인 종료 1회성 감리로는 개발 초기의 구조적 결함을 막을 수 없고, 대규모 차세대 금융/공공 프로젝트의 복합 위험을 통제하기 위해 프로젝트 생애주기별 복합 감리 전략 필수화

#### 한줄 요약
- 감리 유형은 사업 특성에 맞춰 3단계 감리(관문 통제), 상주감리(상시 예방), 특정감리(현안 해결)를 유기적으로 조합한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **감리 3대 주요 유형의 역할 정의**:
  - **단계감리 (Phased Audit, 3단계/2단계)**: 요구정의, 설계, 종료 등 핵심 마일스톤 완료 시점에 정기 투입되어 다음 단계로의 이행 적합성을 판정하는 관문 통제(Quality Gate).
  - **상주감리 (Resident Audit)**: 100억 원 이상 대규모 차세대 사업에서 감리원이 현장에 상주하며 일상적 품질/공정 위험을 조기 색출하는 상시 감리.
  - **특정감리 (Specific Audit)**: 데이터 이행 실패, 심각한 성능 병목, 사업자-발주자 간 계약 분쟁 등 돌발 위기 발생 시 비정기적으로 긴급 투입되는 심층 감사.

</details>

- **마일스톤 관문 통제(Quality Gate Control)**: 전 단계의 시정조치가 '적정'으로 완료되지 않으면 다음 개발 단계(예: 설계 $\rightarrow$ 구현)로의 공식 진입을 차단
- **상주감리의 엄격한 독립성(Role Separation)**: 상주감리원은 문제점을 '발견 및 권고'하는 역할에 한정하며, 코드 작성이나 아키텍처 승인 등 '의사결정'에 직접 참여하는 것을 법적으로 엄격히 금지
- **공통 식별자 기반 전 주기 추적(Audit Trail)**: 1차(요구) 감리 지적사항이 2차(설계) 및 3차(종료) 감리에서 어떻게 해결되고 파급되었는지를 단일 고유 ID로 영구 추적

#### 한줄 요약
- 단계별 게이트 통제, 상주감리의 엄격한 독립성 유지, 특정감리의 돌발 현안 해결, 공통 식별자 전 주기 추적을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **감리 시점 및 투입 방식에 따른 분류 체계**:
  1. **3단계 감리**: 요구정의 단계(1단계) $\rightarrow$ 설계 단계(2단계) $\rightarrow$ 종료 단계(3단계). (총사업비 20억 이상 의무 대상).
  2. **2단계 감리**: 설계 단계(1단계) $\rightarrow$ 종료 단계(2단계). (20억 미만 단기 사업).
  3. **상주감리**: 분석부터 안정화까지 상주 수석감리원 1인 이상 상시 투입.
  4. **특정감리**: 비정기 발동 (성능 BMT 검증, 데이터 마이그레이션 적합성 등).

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 프로젝트 생애주기별 정보시스템 감리 유형 매핑 아키텍처 ]          │
│                                                                         │
│  [ 사업 착수 / 기획 ] ──► [ 요구사항 정의 ] ──► [ 아키텍처 설계 ] ──► [ 구현 / 테스트 ] ──► [ 전개 / 오픈 ] │
│                             │                    │                                   │          │
│  ┌──────────────────────────┼────────────────────┼───────────────────────────────────┼──────────┘
│  │ [ 1. 단계감리 (Phased) ]  ▼                    ▼                                   ▼          │
│  │ ├─ 3단계 감리:      [ 1차 요구정의 감리 ]   [ 2차 설계 감리 ]                  [ 3차 종료 감리 ]│
│  │ └─ 2단계 감리:                             [ 1차 설계 감리 ]                  [ 2차 종료 감리 ]│
│  ├──────────────────────────────────────────────────────────────────────────────────────────────┤
│  │ [ 2. 상주감리 (Resident) ] ◄══════════════════ (전 기간 상주 상시 모니터링) ═══════════════►│
│  ├──────────────────────────────────────────────────────────────────────────────────────────────┤
│  │ [ 3. 특정감리 (Specific) ]                     [ 데이터 이행 특정감리 ]  [ 성능 과부하 특정감리 ]│
│  └──────────────────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 사업 단계별 마일스톤에 맞춘 단계감리와 전 기간을 포괄하는 상주감리, 돌발 이슈 발생 시 투입되는 특정감리의 입체적 결합 구조

| 감리 유형 | 투입 시점 및 주기 | 법적 의무 및 적용 기준 | 핵심 점검 대상 및 산출물 |
|:---|:---|:---|:---|
| **3단계 감리** | 요구정의, 설계, 종료 시점 (각 5일) | **총사업비 20억 원 이상 공공 SW사업** | 과업대비표, ERD, 소스코드, 기능/비기능 시험 |
| **2단계 감리** | 설계, 종료 시점 (각 5일) | 총사업비 20억 원 미만 일반 사업 | 상세 설계서, 아키텍처, 시스템 인수 검수 |
| **상주감리** | 프로젝트 전 기간 상주 (상시) | 대규모 차세대, 고난이도 금융망 구축 | 일상 산출물 품질, 위험 관리대장, 상시 보고서 |
| **특정감리** | 돌발 현안 발생 시 비정기 투입 | 데이터 마이그레이션 오류, 성능 장애 | 특정 쟁점 심층 분석서, 긴급 시정조치 권고 |

#### 한줄 요약
- 3단계 감리(20억 이상 의무), 2단계 감리(20억 미만), 상주감리(상시 밀착), 특정감리(비정기 현안)로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **하이브리드 감리(3단계 + 특정감리) 실행 5단계 프로세스**:
  1. 사업 착수 시 요구정의, 설계, 종료의 3단계 감리 기본 일정 및 예산 확정
  2. 요구정의 감리 수행을 통해 과업 범위 누락 및 불명확한 요구사항 사전 색출
  3. 설계 감리 완료 후 구현 단계에서 대용량 데이터 이행 쿼리 지연 병목 발생
  4. 발주기관이 데이터베이스 전문 감리원을 긴급 투입하는 '데이터 이행 특정감리' 전격 발동
  5. 특정감리 개선안 반영 후 종료 감리를 수행하여 시스템 성공적 오픈 검증

</details>

```text
1. [사업 특성 분석 및 감리 유형 조합 확정]
    ├─ 대상: 차세대 지능형 행정복지 정보시스템 (총사업비 150억 원)
    └─ [결정: 법정 '3단계 감리' 기본 체결 + 고위험 구간 '데이터 이행 특정감리' 옵션 계약]
            │
            ▼
2. [1차 요구정의 단계감리 수행]
    ├─ RFP 요구사항 350개 항목과 요구사항 정의서 1:1 대조
    └─ [지적사항: 개인정보 마스킹 요구사항 12건 누락 색출 ➔ 설계 반영 강제]
            │
            ▼
3. [2차 설계 단계감리 수행]
    ├─ 데이터베이스 ERD 정규화, 인터페이스 연계 규격서, 클라우드 아키텍처 실사
    └─ [지적사항: DB 커넥션 풀 사이징 미흡 및 SPOF 존재 지적 ➔ Multi-AZ 이중화 보완]
            │
            ▼
4. [구현 단계 긴급 특정감리(Specific Audit) 발동]
    ├─ [돌발 위기]: 5,000만 건의 과거 복지 이력 데이터 이행 시 48시간 이상 소요 병목 발생
    ├─ DB 튜닝 수석감리원 2명 긴급 투입 ➔ 대량 배치 파티셔닝 및 병렬 로딩 인덱스 재설계 권고
    └─ [조치 결과: 데이터 이행 소요 시간을 48시간 ➔ 4시간으로 90% 이상 단축 성공]
            │
            ▼
5. [3차 종료 단계감리 및 최종 시스템 오픈]
    ├─ 기능 구현 100% 검증, 성능 부하 시험(5,000 TPS) 및 보안 취약점 0건 검증
    └─ [시정조치 확인보고서 '적정' 통보 ➔ 무장애 안정적 대국민 서비스 오픈]
```

**동작 원리**

1. **시점별 결함 예방(Shift-Left)의 효과**: 1차 요구정의 감리에서 요구사항 결함을 걸러냄으로써 구현 후 재개발 비용의 80%를 사전 예방
2. **상주감리와 PMO의 엄격한 역할 분리**: PMO는 진척 관리와 협력업체 조율을 맡고, 상주감리는 제3자 입장에서 품질 미달과 프로세스 위반을 객관적으로 지적
3. **특정감리의 기동 타격(Precision Strike)**: 프로젝트를 마비시키는 특정 쟁점(예: 성능, 보안, 데이터)에 대해 최고 전문가를 3~5일간 집중 투입하여 프로젝트 좌초 방어
4. **차수 간 연속성(Inter-Phase Continuity)**: 감리법인이 변경되더라도 이전 차수의 감리보고서와 미해결 지적사항을 의무적으로 인수인계받아 다음 차수에서 재실사
5. **예산 효율적 하이브리드 거버넌스**: 무조건적인 고비용 상주감리 대신, 필수 3단계 감리에 취약 구간 특정감리를 결합하여 가성비와 품질 보증 동시 달성

#### 한줄 요약
- 사업 특성 분석, 1차 요구감리, 2차 설계감리, 돌발 위기 시 특정감사 발동, 3차 종료감리 및 성공적 오픈 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **감리 3대 핵심 유형 특성 비교**:
  - 단계감리: 정기 마일스톤 관문 통제 (비용 효율적, 법정 의무).
  - 상주감리: 전 기간 상시 밀착 위험 통제 (고비용, 초대형 사업).
  - 특정감리: 특정 중대 현안 집중 해결 (기동성, 전문성).

</details>

| 비교 항목 | 단계감리 (Phased Audit) | 상주감리 (Resident Audit) | 특정감리 (Specific Audit) |
|:---|:---|:---|:---|
| **투입 방식** | **핵심 마일스톤 시점 (회당 5일 내외)**| **프로젝트 전 기간 상주 (수개월~수년)**| **현안 발생 시 비정기 집중 투입 (3~5일)**|
| **최우선 목적** | **단계별 산출물 적합성 및 관문 통제**| **일상적 공정 위험의 조기 색출 및 예방**| **데이터/성능/분쟁 등 특정 현안 해결**|
| **법적 성격** | **전자정부법상 20억 이상 의무** | 발주기관의 선택적 도입 (고위험군) | 발주기관 요청 시 수시 발동 |
| **비용 부담** | 표준 감리 대가 (가장 경제적) | **고비용 ($3\times \sim 5\times$)** | 투입 인력/기간 비례 단기 비용 |
| **주의할 위험** | 단계 사이의 일상적 위험 누적 사각지대| **PMO와의 역할 혼선 및 셀프 감사 위험**| 전체 시스템 연관 파급 효과 간과 위험 |

#### 한줄 요약
- 단계감리는 정기 관문 통제, 상주감리는 상시 밀착 예방, 특정감리는 돌발 현안 해결에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **감리 유형 운영 시 3대 위험 요소와 엔지니어링 대책**:

</details>
