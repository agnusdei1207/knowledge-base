## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **KPI(Key Performance Indicator)**: 비즈니스 및 기술적 목표 달성 여부를 정량적으로 측정하는 핵심 기준 지표.
- **SLI(Service Level Indicator)**: 서비스 품질(가용성, 응답시간 등)의 직접적 정량 측정 지표.
- **포화(Saturation)**: 시스템 자원 임계치 도달에 따른 처리량 정체 및 응답 지연 현상.
- **꼬리 지연(Tail Latency)**: 상위 1~5%(p95, p99) 요청의 극단적 응답 지연 현상.
- **중단(Outage)**: 서비스 제공 불가로 인한 비즈니스 연속성 훼손 구간.
- **성능 지표 체계(Performance Metric Framework)**: 서비스 품질 평가를 위한 정량적 지표 통합 관리 모델.

</details>

- 정의: **처리량·응답시간·가용성**의 정량 관리 체계
- 필요성: 평균만으로는 **포화·꼬리 지연 식별 불가**

#### 한줄 요약

- 처리 역량·지연·정상 운영 비율의 **통합 관리**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **처리량(Throughput)**: 단위 시간당 성공적으로 완료한 트랜잭션 건수나 데이터 전송량으로, 시스템의 전체적인 처리 규모를 대변하는 지표.
- **응답시간(Response Time)**: 사용자 또는 클라이언트의 요청 송신 시점부터 최종 처리 결과를 수신하기까지 소요된 총 대기 및 실행 시간.
- **백분위수(Percentile, p95/p99)**: 측정된 전체 요청을 정렬했을 때 95% 또는 99%가 특정 시간 이하로 완료됨을 나타내는 통계적 수치로, 평균의 함정을 회피하는 꼬리 지연 분석 도구.
- **관리 목표 체계(Management Objective System)**: 측정 지표(SLI), 내부 달성 목표(SLO), 외부 보상 및 책임 협약(SLA)을 일관성 있게 연결하여 서비스 품질을 관리하는 추적 구조.

</details>

- 처리량·응답시간 분리로 **병목 지점 식별**
- **백분위수**로 평균에 가려진 꼬리 지연 확인
- **SLI·SLO·SLA** 연계로 책임 기준 명확화

#### 한줄 요약

- 분포 기반 지표 분석으로 **서비스 신뢰도 확보**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TPS(Transactions Per Second)**: 1초 동안 시스템이 오류 없이 성공적으로 완료한 비즈니스 거래 건수로, 시스템 용량 산정의 핵심 기준치.
- **RPS(Requests Per Second)**: 초당 처리한 개별 기술적 요청(HTTP/API 등) 횟수로, 세부 호출 성능 판단 기준.
- **가용성(Availability)**: 약정 운영 시간 중 중단 없이 정상 운영된 시간 비율.
- **MTTR(Mean Time To Repair)**: 장애 발생 시점부터 정상화까지 소요된 평균 시간으로, 대응 프로세스 민첩성 지표.

</details>

```text
                         [업무•측정 경계]
                                |
          +---------------------+---------------------+
          |                     |                     |
    [처리량•성공•오류]   [평균•백분위 지연]   [가용성•복구시간]
          |                     |                     |
          +---------------------+---------------------+
                                |
                          [SLI•SLO•SLA]
```

선의 의미: 업무 단위별 처리량, 지연, 가용성 지표 수집을 통한 서비스 수준 관리 체계 관계도.

| 구성요소 | 책임 및 역할 |
|:---|:---|
| 업무•측정 경계 | 거래 단위·기간·성공 기준 확립 |
| 처리량•성공•오류 | 성공 기준의 **TPS·RPS** 집계 |
| 평균•백분위 지연 | 평균·p95·p99 분포 산출 |
| 가용성•복구시간 | **가용성·MTTR** 산출 |
| SLI•SLO•SLA | **SLI·SLO·SLA** 목표 비교 |

#### 한줄 요약

- 동일 경계·성공 기준의 **정합한 성능 지표**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **측정 구간(Measurement Window, 관측 시간대)**: 성능 지표 산출의 통계적 유의성을 확보하기 위해 시작부터 종료 시점까지 일정하게 고정한 모니터링 및 집계 범위.
- **성공 기준(Success Criteria, 정상 응답 조건)**: 기술적 오류(5xx 응답 등)나 비즈니스 취소를 제외하고 최종적으로 사용자에게 유효한 결과를 반환한 정상 처리 판정 규칙.
- **부하 조건(Workload Condition, 워크로드 프로파일)**: 동시 접속 사용자 수, 초당 요청률, 트랜잭션 혼합 비율 등을 조정하여 실 환경과 유사하게 재현하는 시험적 제약 사항.
- **업무•부하•목표 정의(Workload & Target Definition)**: 성능 테스트 수행 전, 비즈니스 거래 단위, 성공 조건, 서비스 목표치를 확정하여 검증 방향성을 수립하는 준비 단계.
- **동시성•요청률 부하 생성(Load Generation)**: 설정된 사용자 동시성 및 요청 빈도 조건에 맞춰 시스템에 실제적인 스트레스와 부하를 가하는 부하 주입 과정.
- **완료•오류•구간 기록(Metric Logging, 측정 데이터 로깅)**: 각 요청의 시작/종료 시각, HTTP 상태 코드, 트랜잭션 추적 ID 등을 시스템 및 APM 등에 남겨 사후 분석을 가능케 하는 정보 수집 단계.
- **TPS•지연•가용성 산출(Metric Calculation)**: 수집된 원시 로그 데이터를 기반으로 동일 측정 구간 내 총 처리량, 백분위 지연 분포, 서비스 가동 비율 등을 수치화하여 계산하는 분석 과정.

</details>

```text
측정 책임자
     │ 1. 업무·부하·목표 정의
     │    거래•기간•성공•SLO 확정
     ▼
부하 발생기
     │ 2. 동시성·요청률 부하 생성
     │    시험 부하 조건 재현
     ▼
서비스
     │ 3. 완료·오류·구간 기록
     │    종료시각•상태•추적 수집
     ▼
수집•분석기
     │ 4. TPS·지연·가용성 산출
     │    분모•백분위•중단 계산
     ▼
SLO 충족•병목 판정
```

### 동작 원리

1. **업무·부하·목표 정의**: 측정 구간·성공 기준 확정
2. **동시성·요청률 부하 생성**: 시험 부하 조건 재현
3. **완료·오류·구간 기록**: 시각·상태·추적 정보 수집
4. **TPS·지연·가용성 산출**: 목표 충족 여부 판정

#### 한줄 요약

- 거래별 성공 횟수·지연의 **동일 구간 산출**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **업무 거래(Business Transaction, 비즈니스 로직 단위)**: 사용자 관점에서 로그인, 결제 등 하나의 완전한 비즈니스 목적을 달성하기 위해 묶여서 실행되는 내부 시스템 요청들의 논리적 집합.
- **처리량•응답시간•가용성 비교(Metric Comparison)**: 시스템을 평가할 때 단순 용량, 응답 민첩성, 중단 없는 연속성을 상호 교차 검증하여 특정 지표 편향에 의한 왜곡을 방지하는 다각도 분석 기법.

</details>

| 성능 지표 | 처리량 (Throughput) | 응답시간 (Latency) | 가용성 (Availability) |
|:---|:---|:---|:---|
| 적용 기준 | **업무 거래** 완수량 | 사용자 체감 속도 | 정상 운영 시간 비율 |
| 핵심 특징 | **처리량**으로 최대 용량 판단 | **응답시간** 분포로 병목 판단 | 가동 비율로 신뢰성 판단 |
| 한계/단점 | 지연·오류율 미반영 | 평균이 **꼬리 지연** 은폐 | 단기 측정의 통계 왜곡 |

> 요약: 성능의 다차원적 지표인 처리량, 응답시간, 가용성을 상호 보완적으로 활용하여 단일 지표의 한계 극복.

#### 한줄 요약

- 처리량·응답시간·가용성의 **다차원 균형**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SLO(Service Level Objective, 서비스 수준 목표)**: 도출된 SLI 지표에 대해 조직 내부적으로 설정한 현실적이고 엄격한 목표 달성 기준치(예: 결제 성공률 99.9%).
- **SLA(Service Level Agreement, 서비스 수준 협약)**: 서비스 제공자와 고객 간에 체결된 공식 계약으로, SLO 미달 시 부과되는 페널티나 손해배상 등의 외부 책임 소재를 명시.
- **오류율(Error Rate, 트랜잭션 실패율)**: 총 처리된 요청 횟수 중 타임아웃, 예외 발생 등으로 인해 실패로 귀결된 요청의 비중을 산출한 지표.
- **부하 대표성(Workload Representativeness)**: 테스트 환경에서 생성한 가상 사용자 동시성 및 트랜잭션 비율이 실제 운영 환경의 최고 피크 타임 부하 특성을 얼마나 정밀하게 모사하는지를 나타내는 정도.

</details>

| 실무 문제점 | 대응 방안 (대책) | 기대 효과 |
|:---|:---|:---|
| 거래와 API 요청 기준 혼용 | **업무 거래**와 RPS 분리 측정 | 지표 해석 일관성 확보 |
| 평균이 극단 지연 은폐 | **p95·p99·오류율** 병행 | 포화·경합 병목 식별 |
| 실제 트래픽과 시험 부하 괴리 | 운영 로그 기반 **부하 대표성** 확보 | 한계 용량 사전 검증 |

- 내부 **SLO**와 외부 **SLA**의 책임 기준 연계

#### 한줄 요약

- **포화점·p99 급증 지점** 기반 증설 판단

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **다차원 성능 판단(Multidimensional Performance Evaluation)**: 어느 하나의 단일 지표에 얽매이지 않고 처리량, 지연시간, 오류율, 가용성을 총체적이고 입체적으로 교차 분석하여 시스템 성능을 확정하는 평가 철학.
- **용량 한계(Capacity Limit, 임계 성능점)**: 시스템에 유입되는 부하가 계속 늘어남에도 불구하고 초당 처리량이 포화되어 정체되고 대기 지연과 시스템 오류가 지수 함수적으로 폭증하는 극단적 한계 시점.
- **지표 채택(Metric Selection)**: 시스템 성격에 맞추어 업무 서비스 경계별 중요도를 산정하고, 이를 기반으로 TPS, p99 백분위 응답시간, 장애 가용성을 최우선 모니터링 SLO 지표로 엄격히 확정하는 활동.

</details>

- **용량 한계** 도달 전 처리량·p99 기반 증설 적용

#### 한줄 요약

- 처리량 정체·p99 급증 전 **선제적 용량 증설**
