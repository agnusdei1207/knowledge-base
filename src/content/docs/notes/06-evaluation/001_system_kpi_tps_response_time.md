## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **KPI(Key Performance Indicator)**: 목표 달성 여부를 판정하는 핵심 성과 지표.
- **SLI(Service Level Indicator)**: 서비스 수준을 직접 측정한 지표임.
- **포화(Saturation)**: 부하 증가에도 처리량이 더 이상 늘지 않는 상태를 의미함.
- **꼬리 지연(Tail Latency)**: 일부 요청의 응답시간이 상위 백분위에서 길어지는 현상.
- **중단(Outage / Downtime)**: 서비스가 정상적으로 제공되지 못하는 장애 구간을 말함.
- **성능 지표 체계(Performance Metric Framework)**: 처리량•응답시간•오류•가용성으로 서비스 목표 달성을 판정하는 지표 구조.

</details>

- 정의/개념: **KPI**로 처리량•응답시간•가용성 목표를 판정하는 **성능 지표 체계** 구축.
- 배경/필요성: 평균값 기반 측정 시 부하 증가에 따른 **포화**, **꼬리 지연**, **중단** 식별의 한계 존재.

#### 한줄 요약

- 처리한 일의 양•기다린 시간•정상 제공 비율을 서로 다른 숫자로 확인하는 것이 핵심이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **처리량(Throughput)**: 단위 시간당 성공적으로 완료한 작업량이나 데이터 전송량.
- **응답시간(Response Time)**: 요청 송신 시점부터 최종 응답 수신까지 소요된 시간임.
- **백분위수(Percentile, p95•p99)**: 전체 요청의 95%•99%가 해당 시간 이하로 완료됨을 나타내는 꼬리 지연 지표.
- **관리 목표 체계(Management Objective System)**: 서비스 수준 지표•목표•협약을 연결하여 측정값, 내부 목표, 외부 책임을 추적하는 구조를 형성함.

</details>

- **처리량**과 **응답시간**의 분리된 측정 축 적용.
- 평균과 **백분위수**를 활용한 꼬리 지연 분포 분석.
- **관리 목표 체계**를 통한 SLI•SLO•SLA 목표 및 책임 추적.

#### 한줄 요약

- 평균이 빨라도 일부 요청이 오래 기다리거나 실패하면 백분위수와 오류율에 드러남이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **TPS(Transactions Per Second)**: 1초 동안 성공적으로 완료한 업무 거래 건수를 나타냄.
- **RPS(Requests Per Second)**: 1초에 처리한 개별 HTTP/API 요청 수.
- **가용성(Availability)**: 약정한 운영 시간 중 정상 서비스를 제공한 시간의 비율을 의미함.
- **MTTR(Mean Time To Repair)**: 장애 발생 후 정상 상태로 복구하기까지의 평균 소요 시간.

</details>

```text
                         [업무•측정 경계]
                                |
          +---------------------+---------------------+
          |                     |                     |
[처리량•성공•오류]   [평균•백분위 지연]   [가용성•복구시간]
          |                     |                     |
          +---------------------+---------------------+
                                |
                         [SLI•SLO•SLA]
```

선의 의미: 동일 업무•측정 경계 내 처리량, 지연, 가용성 지표와 SLI•SLO•SLA 관리 체계의 결합 관계 표현.

| 구성요소 | 책임 |
|:---|:---|
| 업무•측정 경계 | 거래•요청•기간•성공 정의 |
| 처리량•성공•오류 | **TPS**•**RPS** 집계 |
| 평균•백분위 지연 | 평균•백분위수 분포 |
| 가용성•복구시간 | **가용성**•**MTTR** 집계 |
| SLI•SLO•SLA | **SLI** 측정값과 목표•책임 연결 |

#### 한줄 요약

- 같은 거래•기간•성공 기준으로 측정해야 지표를 서로 비교할 수 있다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **측정 구간(Measurement Window)**: 지표의 시작•종료 시점과 집계 대상을 동일하게 설정한 관측 범위.
- **성공 기준(Success Criteria)**: 오류나 취소를 제외하고 정상 처리로 인정할 판정 규칙임.
- **부하 조건(Workload Condition)**: 동시 사용자 수•요청률•업무 비율•지속시간으로 재현할 작업량 기준을 지정함.
- **업무•부하•목표 정의(Workload & Target Definition)**: 거래•기간•성공 기준 및 서비스 목표와 시험 부하를 확정하는 단계.
- **동시성•요청률 부하 생성(Load Generation)**: 설정한 동시 사용자 수와 요청률로 목표 부하를 재현하는 과정을 말함.
- **완료•오류•구간 기록(Metric Logging)**: 요청 종료시각•상태코드•추적 정보를 수집 및 저장하는 단계.
- **TPS•지연•가용성 산출(Metric Calculation)**: 동일 측정 구간 내 처리량•백분위 지연•중단 시간을 계산함.

</details>

```text
측정 책임자
     │ 1. 업무•부하•목표 정의
     │    거래•기간•성공•SLO 확정
     ▼
부하 발생기
     │ 2. 동시성•요청률 부하 생성
     │    시험 부하 조건 재현
     ▼
서비스
     │ 3. 완료•오류•구간 기록
     │    종료시각•상태•추적 수집
     ▼
수집•분석기
     │ 4. TPS•지연•가용성 산출
     │    분모•백분위•중단 계산
     ▼
SLO 충족•병목 판정
```

### 동작 원리

1. **업무•부하•목표 정의**: **측정 구간**•**성공 기준**•**부하 조건** 확정.
2. **동시성•요청률 부하 생성**: **동시성•요청률 부하 생성**을 통한 시험 조건 재현.
3. **완료•오류•구간 기록**: **완료•오류•구간 기록**을 통한 추적 정보 수집.
4. **TPS•지연•가용성 산출**: **TPS•지연•가용성 산출**을 통한 분모•백분위•중단 계산.

#### 한줄 요약

- 요청 시작과 완료 기록을 짝지어 지연을 구하고 성공 건수를 시간 단위로 합침이 핵심이다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **업무 거래(Business Transaction)**: 사용자 관점에서 하나의 작업 목적을 완료하는 내부 요청들의 집합.
- **처리량•응답시간•가용성 비교(Metric Comparison)**: 처리 용량•체감 속도•서비스 지속성을 다각도로 비교 검증함.

</details>

| 성능 지표 | 처리량 | 응답시간 | 가용성 |
|:---|:---|:---|:---|
| 적용 기준 | **업무 거래** 처리량 확인 | 사용자 체감 속도 측정 | 서비스 지속 여부 측정 |
| 핵심 특징 | **처리량**으로 용량 판단 | **응답시간**으로 지연 판단 | **가용성**으로 지속성 판단 |
| 한계 | 실패 건수 제외 | **꼬리 지연** 은폐 | 짧은 측정 기간 왜곡 |

> 요약: **처리량•응답시간•가용성 비교**를 통한 지표별 한계 분석.

#### 한줄 요약

- 처리량은 용량, 응답시간은 체감, 가용성은 지속성을 나타냄이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **SLO(Service Level Objective)**: SLI 지표에 대해 내부적으로 설정한 목표 달성 값.
- **SLA(Service Level Agreement)**: 측정 기준•목표•손해배상 등 책임을 명시한 계약임.
- **오류율(Error Rate)**: 전체 요청 중 실패로 판정된 요청이 차지하는 비율을 의미함.
- **부하 대표성(Workload Representativeness)**: 피크 업무 비율•동시성이 실제 운영환경을 충분히 반영하는 정도.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거래•요청 경계 혼용 | **업무 거래**•성공•측정 기간을 고정하고 RPS와 분리 | 업무 의미 일관성 확보 |
| 평균이 장기 지연을 은폐 | **p95**•**p99**•**오류율** 병행 측정 | 포화 구간 식별 |
| 정상 부하만 측정 | **부하 대표성** 확보 | 실제 처리 용량 검증 |

- **SLO**의 내부 목표 활용 및 **SLA**의 외부 책임 기준 적용.

#### 한줄 요약

- 출시 전 부하를 늘리며 TPS가 멈추고 p99가 급증하는 포화점을 찾음이 핵심이다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **다차원 성능 판단(Multidimensional Performance Evaluation)**: 처리량•지연•오류•가용성을 종합적으로 분석하여 성능을 평가하는 방식.
- **용량 한계(Capacity Limit)**: 부하 증가 시 처리량이 정체되고 지연 및 오류가 급증하는 임계 시점임.
- **지표 채택(Metric Selection)**: 업무 경계별 TPS•p99 응답시간•가용성을 서비스 수준 목표 지표로 확정함.

</details>

- **지표 채택**과 **다차원 성능 판단**을 통한 **용량 한계** 및 증설 시점 결정.

#### 한줄 요약

- 빠른 평균 하나가 아니라 용량•느린 요청•실패•중단을 함께 보고 규모를 결정하는 것이 핵심이다.
