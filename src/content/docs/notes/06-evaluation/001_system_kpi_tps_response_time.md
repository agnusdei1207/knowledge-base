## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **KPI(Key Performance Indicator, 핵심 성과 지표)**: 시스템의 비즈니스 및 기술적 목표 달성 여부를 정량적으로 판정하고 모니터링하기 위해 설정하는 핵심 측정 기준.
- **SLI(Service Level Indicator, 서비스 수준 지표)**: 사용자 관점에서 제공되는 서비스의 품질 수준(가용성, 응답시간 등)을 직접적으로 측정하고 추적하는 정량적 데이터.
- **포화(Saturation, 자원 포화)**: 시스템 자원이 임계치에 도달하여 부하가 증가함에도 처리량이 늘지 않고 대기열이 쌓여 응답 지연이 급증하는 병목 상태.
- **꼬리 지연(Tail Latency, 상위 백분위 지연)**: 전체 응답시간 분포 중 상위 1~5%(p95, p99)의 극단적으로 느린 소수 요청이 겪는 현상으로, 전체적인 사용자 체감 품질 저하의 주된 원인.
- **중단(Outage / Downtime, 장애 및 가동 중지)**: 서비스가 정상적으로 제공되지 못해 비즈니스 연속성이 훼손되는 장애 구간으로, 고가용성 설계의 직접적인 방어 대상.
- **성능 지표 체계(Performance Metric Framework)**: 처리량, 응답시간, 오류, 가용성 등 다양한 차원의 지표를 통합하여 서비스 상태를 다각도로 평가하고 목표 달성을 판정하는 구조적 체계.

</details>

- 정의/개념: 비즈니스 요구사항을 반영한 **KPI**를 기반으로 처리량, 응답시간, 가용성 목표를 수치화하여 달성 여부를 판정하는 통합 **성능 지표 체계**의 구축.
- 배경/필요성: 단순 평균값 위주의 성능 측정만으로는 임계 부하 상황에서의 자원 **포화**, 사용자 불만을 야기하는 **꼬리 지연**, 그리고 서비스 **중단**의 근본 원인을 조기에 식별하고 대응하는 데 한계가 존재하기 때문.

#### 한줄 요약

- 서비스의 실질적인 처리 역량, 응답 지연, 그리고 정상 운영 비율을 독립적인 수치로 도출하여 입체적으로 점검하는 측정 프레임워크 구현

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **처리량(Throughput, 시스템 처리 용량)**: 단위 시간당 성공적으로 완료한 트랜잭션 건수나 데이터 전송량으로, 시스템의 전체적인 처리 규모를 대변하는 지표.
- **응답시간(Response Time, 서비스 지연 시간)**: 사용자 또는 클라이언트의 요청 송신 시점부터 최종 처리 결과를 수신하기까지 소요된 총 대기 및 실행 시간.
- **백분위수(Percentile, p95•p99)**: 측정된 전체 요청을 정렬했을 때 95% 또는 99%가 특정 시간 이하로 완료됨을 나타내는 통계적 수치로, 평균의 함정을 회피하는 꼬리 지연 분석 도구.
- **관리 목표 체계(Management Objective System)**: 측정 지표(SLI), 내부 달성 목표(SLO), 외부 보상 및 책임 협약(SLA)을 일관성 있게 연결하여 서비스 품질을 관리하는 추적 구조.

</details>

- **처리량**과 **응답시간**의 분리된 측정 축 적용: 용량과 지연을 분리하여 부하에 따른 시스템의 한계점 및 병목 양상을 정확히 도출.
- 평균과 **백분위수**를 활용한 꼬리 지연 분포 분석: 평균값에 가려진 소수의 극단적 지연 사례를 식별하여 실질적 체감 성능을 향상.
- **관리 목표 체계**를 통한 책임 추적: SLI 기반의 실측값과 SLO/SLA를 연동하여 성능 저하 시 내부 조치 및 외부 책임 소재를 명확히 규명.

#### 한줄 요약

- 대다수의 평균 응답이 신속하더라도 일부 소수 요청의 꼬리 지연이나 오류가 전체 서비스 신뢰도를 하락시킴을 반영한 분산 지표 분석 적용

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **TPS(Transactions Per Second, 초당 트랜잭션 수)**: 1초 동안 시스템이 오류 없이 성공적으로 완료한 비즈니스 거래 건수로, 시스템 용량 산정의 핵심 기준치.
- **RPS(Requests Per Second, 초당 요청 수)**: 초당 처리한 개별 HTTP/API 등 기술적 요청의 횟수로, TPS를 구성하는 세부 호출 성능 판단 기준.
- **가용성(Availability, 서비스 가용률)**: 약정된 총 운영 시간 중 중단 없이 정상적으로 서비스를 제공한 시간의 비율(%)을 나타내는 신뢰성 지표.
- **MTTR(Mean Time To Repair, 평균 복구 시간)**: 장애 발생 시점부터 원인 파악 및 시스템 정상화까지 소요되는 평균 시간으로, 장애 대응 프로세스의 민첩성을 대변.

</details>

```text
                         [업무•측정 경계]
                                |
          +---------------------+---------------------+
          |                     |                     |
[처리량•성공•오류]   [평균•백분위 지연]   [가용성•복구시간]
          |                     |                     |
          +---------------------+---------------------+
                                |
                         [SLI•SLO•SLA]
```

선의 의미: 동일한 비즈니스 업무 및 측정 경계 내에서 처리량, 지연, 가용성 측정 지표가 수집되어 SLI/SLO/SLA 기반의 서비스 수준 관리 체계로 통합•평가되는 관계도.

| 구성요소 | 책임 및 역할 |
|:---|:---|
| 업무•측정 경계 | 서비스 특성에 맞는 거래 단위, 측정 기간, 그리고 정상 처리(성공)의 명확한 기준 확립 |
| 처리량•성공•오류 | 전체 요청 중 성공 처리된 비중을 바탕으로 실질적인 **TPS** 및 **RPS** 정량 집계 |
| 평균•백분위 지연 | 사용자가 체감하는 대기시간의 평균값 및 극단값을 식별하기 위한 백분위수 분포 도출 |
| 가용성•복구시간 | 시스템 다운타임을 최소화하고 지속성을 보장하기 위한 **가용성** 퍼센티지 및 **MTTR** 산출 |
| SLI•SLO•SLA | 산출된 실측 지표(**SLI**)를 내부 품질 목표(**SLO**) 및 고객 보상 기준(**SLA**)과 비교 분석 |

#### 한줄 요약

- 산발적인 성능 데이터가 아닌, 동일한 측정 경계와 성공 판정 기준을 바탕으로 도출된 정합성 있는 성능 지표 체계 구성

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **측정 구간(Measurement Window, 관측 시간대)**: 성능 지표 산출의 통계적 유의성을 확보하기 위해 시작부터 종료 시점까지 일정하게 고정한 모니터링 및 집계 범위.
- **성공 기준(Success Criteria, 정상 응답 조건)**: 기술적 오류(5xx 응답 등)나 비즈니스 취소를 제외하고 최종적으로 사용자에게 유효한 결과를 반환한 정상 처리 판정 규칙.
- **부하 조건(Workload Condition, 워크로드 프로파일)**: 동시 접속 사용자 수, 초당 요청률, 트랜잭션 혼합 비율 등을 조정하여 실 환경과 유사하게 재현하는 시험적 제약 사항.
- **업무•부하•목표 정의(Workload & Target Definition)**: 성능 테스트 수행 전, 비즈니스 거래 단위, 성공 조건, 서비스 목표치를 확정하여 검증 방향성을 수립하는 준비 단계.
- **동시성•요청률 부하 생성(Load Generation)**: 설정된 사용자 동시성 및 요청 빈도 조건에 맞춰 시스템에 실제적인 스트레스와 부하를 가하는 부하 주입 과정.
- **완료•오류•구간 기록(Metric Logging, 측정 데이터 로깅)**: 각 요청의 시작/종료 시각, HTTP 상태 코드, 트랜잭션 추적 ID 등을 시스템 및 APM 등에 남겨 사후 분석을 가능케 하는 정보 수집 단계.
- **TPS•지연•가용성 산출(Metric Calculation)**: 수집된 원시 로그 데이터를 기반으로 동일 측정 구간 내 총 처리량, 백분위 지연 분포, 서비스 가동 비율 등을 수치화하여 계산하는 분석 과정.

</details>

```text
측정 책임자
     │ 1. 업무•부하•목표 정의
     │    거래•기간•성공•SLO 확정
     ▼
부하 발생기
     │ 2. 동시성•요청률 부하 생성
     │    시험 부하 조건 재현
     ▼
서비스
     │ 3. 완료•오류•구간 기록
     │    종료시각•상태•추적 수집
     ▼
수집•분석기
     │ 4. TPS•지연•가용성 산출
     │    분모•백분위•중단 계산
     ▼
SLO 충족•병목 판정
```

### 동작 원리

1. **업무•부하•목표 정의**: 측정의 기준점이 될 **측정 구간**, 정상 처리를 판별할 **성공 기준**, 부하 발생 패턴을 규정하는 **부하 조건**을 명확하게 수립하여 목표를 확정한다.
2. **동시성•요청률 부하 생성**: 부하 발생 도구를 통해 가상 사용자 수와 요청 비율을 조절해가며 사전 정의된 시험 부하를 시스템에 지속적으로 주입한다.
3. **완료•오류•구간 기록**: 트랜잭션별 처리 시작과 종료 시점, 응답 상태 등을 모니터링 도구를 통해 실시간 추적 정보로 안전하게 수집 및 보관한다.
4. **TPS•지연•가용성 산출**: 로깅된 데이터를 취합하여 최종적인 누적 성공 건수 기반의 산출식으로 **TPS**, **백분위 지연**, **가동 시간 비율**을 계산하고 목표 충족 여부를 판정한다.

#### 한줄 요약

- 트랜잭션의 시작과 완료 시점을 쌍으로 기록하여 정밀한 지연시간을 구하고, 단위 시간당 성공 횟수를 합산하는 데이터 중심의 산출 구조 확립

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **업무 거래(Business Transaction, 비즈니스 로직 단위)**: 사용자 관점에서 로그인, 결제 등 하나의 완전한 비즈니스 목적을 달성하기 위해 묶여서 실행되는 내부 시스템 요청들의 논리적 집합.
- **처리량•응답시간•가용성 비교(Metric Comparison)**: 시스템을 평가할 때 단순 용량, 응답 민첩성, 중단 없는 연속성을 상호 교차 검증하여 특정 지표 편향에 의한 왜곡을 방지하는 다각도 분석 기법.

</details>

| 성능 지표 | 처리량 (Throughput) | 응답시간 (Latency) | 가용성 (Availability) |
|:---|:---|:---|:---|
| 적용 기준 | 사용자 관점의 논리적 **업무 거래** 완수량 산정 | 시스템 응답에 대한 실제 사용자 체감 속도 정량화 | 정해진 서비스 시간 동안 시스템의 지속 운영 여부 측정 |
| 핵심 특징 | **처리량** 증가 추이를 통해 시스템 최대 수용 용량 판단 | **응답시간**의 분포 추이를 통해 병목 및 성능 저하 판단 | 전체 운용 시간 대비 정상 가동 시간 비율로 시스템 신뢰성 검증 |
| 한계/단점 | 단일 건당 처리 지연시간이나 오류 실패 비율 반영 불가 | **꼬리 지연** 등 소수의 극단적 대기시간이 평균에 의해 은폐될 위험 | 단기적 측정이나 간헐적 장애 시 가용성 비율의 통계적 왜곡 발생 |

> 요약: 성능의 각기 다른 차원을 보여주는 **처리량, 응답시간, 가용성 지표를 상호 보완적**으로 활용하여 단일 지표의 한계를 극복.

#### 한줄 요약

- 시스템의 수용 능력을 나타내는 처리량, 서비스 쾌적성을 의미하는 응답시간, 안정적 운영을 대변하는 가용성 지표 간의 다차원적 균형 유지 필수

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **SLO(Service Level Objective, 서비스 수준 목표)**: 도출된 SLI 지표에 대해 조직 내부적으로 설정한 현실적이고 엄격한 목표 달성 기준치(예: 결제 성공률 99.9%).
- **SLA(Service Level Agreement, 서비스 수준 협약)**: 서비스 제공자와 고객 간에 체결된 공식 계약으로, SLO 미달 시 부과되는 페널티나 손해배상 등의 외부 책임 소재를 명시.
- **오류율(Error Rate, 트랜잭션 실패율)**: 총 처리된 요청 횟수 중 타임아웃, 예외 발생 등으로 인해 실패로 귀결된 요청의 비중을 산출한 지표.
- **부하 대표성(Workload Representativeness)**: 테스트 환경에서 생성한 가상 사용자 동시성 및 트랜잭션 비율이 실제 운영 환경의 최고 피크 타임 부하 특성을 얼마나 정밀하게 모사하는지를 나타내는 정도.

</details>

| 실무 문제점 | 대응 방안 (대책) | 기대 효과 |
|:---|:---|:---|
| 거래 단위와 단일 API 요청 기준의 혼용 및 왜곡 | 사용자 관점 **업무 거래** 기준 성공 판정과 기술적 시스템 단위의 단일 API RPS 측정을 철저히 분리 적용 | 측정 데이터의 비즈니스 의미 일관성 및 지표 해석의 혼선 방지 |
| 평균 지연시간만 주시하여 극단적 지연 및 체감 성능 하락 방치 | 상위 백분위 지표(**p95**, **p99**)와 **오류율**을 필수 병행 측정 지표로 대시보드에 구성 | 시스템 포화 및 자원 경합이 유발하는 숨겨진 병목 구간 선제적 식별 |
| 실제 트래픽과 괴리된 단순 패턴의 정상 부하 한정 테스트 | 운영 환경 로그를 분석하여 실 사용 비율과 피크 동시성을 반영한 실전적 **부하 대표성** 획득 | 오픈 전 실제 서비스 한계 용량을 검증하고 인프라 조기 튜닝 기회 확보 |

- 내부 관리용 엄격한 **SLO** 목표를 수립하고, 이를 바탕으로 비즈니스 계약 책임을 규정하는 **SLA** 체계로 확립하여 지표의 구속력 강화.

#### 한줄 요약

- 부하 테스트 수행 시 시스템 처리량이 더 이상 상승하지 않고 상위 백분위 지연(p99)이 급증하는 포화점(Saturation Point)의 정확한 도출 필수

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **다차원 성능 판단(Multidimensional Performance Evaluation)**: 어느 하나의 단일 지표에 얽매이지 않고 처리량, 지연시간, 오류율, 가용성을 총체적이고 입체적으로 교차 분석하여 시스템 성능을 확정하는 평가 철학.
- **용량 한계(Capacity Limit, 임계 성능점)**: 시스템에 유입되는 부하가 계속 늘어남에도 불구하고 초당 처리량이 포화되어 정체되고 대기 지연과 시스템 오류가 지수 함수적으로 폭증하는 극단적 한계 시점.
- **지표 채택(Metric Selection)**: 시스템 성격에 맞추어 업무 서비스 경계별 중요도를 산정하고, 이를 기반으로 TPS, p99 백분위 응답시간, 장애 가용성을 최우선 모니터링 SLO 지표로 엄격히 확정하는 활동.

</details>

- 시스템의 안정적 운용을 위해 합리적 **지표 채택**과 **다차원 성능 판단**을 기반으로 선제적 **용량 한계** 분석 및 적정 인프라 증설 시점 결정 체계 내재화.

#### 한줄 요약

- 눈속임하기 쉬운 단순 평균값 지표에서 탈피하여 용량, 꼬리 지연, 실패율, 가동 중단율을 포괄적으로 진단하는 통합 모니터링 체계 적용
