## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **핵심 성과 지표(Key Performance Indicator, KPI)**: 시스템 목표 달성 여부를 정량적으로 평가하는 핵심 관리 지표.
- **서비스 수준 지표(Service Level Indicator, SLI)**: 가용성·응답시간 등 서비스 품질을 직접 측정한 정량적 관측치.
- **포화(Saturation)**: 시스템 자원 한계 도달에 따른 처리량 정체 및 대기 지연 급증 현상.
- **꼬리 지연(Tail Latency)**: p95·p99 등 상위 극단 구간에서 발생하는 긴 응답 지연.
- **서비스 중단(Service Outage, 중단)**: 장애로 인해 정상적인 서비스 제공이 불가능한 상태.
- **성능 지표 체계(Performance Metric Framework)**: 시스템 품질을 입체적으로 측정·통제하는 정량 지표 통합 관리 모델.
- **시스템 성능 지표(System Performance Key Performance Indicators, System KPI)**: TPS·응답시간·처리량·가용성을 축으로 시스템 처리 역량과 서비스 연속성을 정량화하는 핵심 평가 지표.

</details>

- 정의/개념: **처리량·응답시간·가용성** 기반 시스템 처리 성능과 안정성을 정량화하는 관리 체계
- 배경/필요성: 평균 지연만으로는 **포화·꼬리 지연** 식별 불가

#### 한줄 요약

- 처리 역량·지연·정상 운영 비율의 **통합 관리**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **처리량(Throughput)**: 단위 시간당 성공적으로 완료한 트랜잭션 또는 데이터 전송량.
- **응답시간(Response Time)**: 요청 송신부터 최종 결과 수신까지 소요된 총 대기·실행 시간.
- **백분위수(Percentile)**: 전체 측정값을 정렬해 특정 비율 이하의 지연 시간을 나타내는 통계 척도.
- **관리 목표 체계(Management Objective System)**: SLI 지표 측정치와 SLO 목표치를 SLA 계약과 연계하는 관리 구조.

</details>

- 처리량·응답시간 분리로 **병목 지점 식별**
- **백분위수** 기반 평균에 가려진 꼬리 지연 확인
- **SLI·SLO·SLA** 연계로 책임 기준 명확화

#### 한줄 요약

- 분포 기반 지표 분석으로 **서비스 신뢰도 확보**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **초당 트랜잭션 수(Transactions Per Second, TPS)**: 1초 동안 성공적으로 완료한 비즈니스 거래 건수.
- **초당 요청 수(Requests Per Second, RPS)**: 초당 처리된 개별 네트워크 및 API 호출 횟수.
- **가용성(Availability)**: 전체 약정 운영 시간 중 정상 가동된 시간의 백분율.
- **평균 복구 시간(Mean Time To Repair, MTTR)**: 장애 발생부터 정상 가동까지 소요된 평균 수리 시간.

</details>

```text
                         [업무•측정 경계]
                                |
          +---------------------+---------------------+
          |                     |                     |
    [처리량•성공•오류]   [평균•백분위 지연]   [가용성•복구시간]
          |                     |                     |
          +---------------------+---------------------+
                                |
                          [SLI•SLO•SLA]
```

선의 의미: 업무 단위별 처리량, 지연, 가용성 지표 수집을 통한 서비스 수준 관리 체계 관계도.

| 구성요소 | 책임 |
|:---|:---|
| 업무•측정 경계 | 거래 단위·기간·성공 기준 확립 |
| 처리량•성공•오류 | 성공 기준의 **TPS**•**RPS** 집계 |
| 평균•백분위 지연 | 평균·p95·p99 분포 산출 |
| 가용성•복구시간 | **가용성**•**MTTR** 산출 |
| SLI•SLO•SLA | **SLI·SLO·SLA** 목표 비교 |

#### 한줄 요약

- 동일 경계·성공 기준의 **정합한 성능 지표**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **측정 구간(Measurement Window)**: 통계적 유의성 확보를 위해 고정한 모니터링 시간 범위.
- **성공 기준(Success Criteria)**: 정상 처리 여부를 판정하는 유효 응답 규칙.
- **부하 조건(Workload Condition)**: 동시성·요청률·거래 비율을 재현하는 시험 환경 조건.
- **부하 발생기(Load Generator)**: 대상 시스템에 인위적 동시 요청을 주입하는 시험 도구.

</details>

```text
측정 책임자
     │ 1. 업무·부하·목표 정의
     │    거래•기간•성공•SLO 확정
     ▼
부하 발생기
     │ 2. 동시성·요청률 부하 생성
     │    시험 부하 조건 재현
     ▼
서비스
     │ 3. 완료·오류·구간 기록
     │    종료시각•상태•추적 수집
     ▼
수집•분석기
     │ 4. TPS·지연·가용성 산출
     │    분모•백분위•중단 계산
     ▼
SLO 충족•병목 판정
```

**동작 원리**

1. **업무·부하·목표 정의**: 측정 구간·성공 기준 확정
2. **동시성·요청률 부하 생성**: 시험 부하 조건 재현
3. **완료·오류·구간 기록**: 시각·상태·추적 정보 수집
4. **TPS·지연·가용성 산출**: 목표 충족 여부 판정

#### 한줄 요약

- 거래별 성공 횟수·지연의 **동일 구간 산출**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **업무 거래(Business Transaction)**: 비즈니스 목적을 달성하는 논리적 작업 완수 단위.

</details>

| 성능 지표 | 처리량 (Throughput) | 응답시간 (Latency) | 가용성 (Availability) |
|:---|:---|:---|:---|
| 적용 기준 | **업무 거래** 완수량 | 사용자 체감 속도 | 정상 운영 시간 비율 |
| 핵심 특징 | **처리량** 기반 최대 용량 판단 | **응답시간** 분포로 병목 판단 | 가동 비율로 신뢰성 판단 |
| 한계 | 지연·오류율 미반영 | 평균이 **꼬리 지연** 은폐 | 단기 측정의 통계 왜곡 |

> 요약: 처리량·응답시간·가용성을 교차 대조하여 단일 지표 편향을 방지하는 다차원 성능 판단 체계 확립.

#### 한줄 요약

- 처리량·응답시간·가용성의 **다차원 균형**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **서비스 수준 목표(Service Level Objective, SLO)**: SLI 지표에 대해 조직 내부적으로 확정한 정량 목표치.
- **서비스 수준 협약(Service Level Agreement, SLA)**: 서비스 제공자와 고객 간 체결한 공식 품질 계약 및 보상 기준.
- **오류율(Error Rate)**: 총 요청 중 실패 또는 타임아웃이 발생한 요청 비율.
- **부하 대표성(Workload Representativeness)**: 시험 부하가 운영 피크 트래픽의 특성을 모사하는 정도.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거래와 API 요청 기준 혼용 | **업무 거래** 및 RPS 분리 측정 | 지표 해석 일관성 확보 |
| 평균이 극단 지연 은폐 | **p95·p99·오류율** 병행 | 포화·경합 병목 식별 |
| 실제 트래픽과 시험 부하 괴리 | 운영 로그 기반 **부하 대표성** 확보 | 한계 용량 사전 검증 |

#### 한줄 요약

- **포화점·p99 급증 지점** 기반 증설 판단

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **용량 한계(Capacity Limit)**: 부하 증가에도 처리량이 포화되고 지연이 급증하는 임계 성능점.

</details>

- **용량 한계** 도달 전 처리량·p99 기반 증설 적용

#### 한줄 요약

- 처리량 정체·p99 급증 전 **선제적 용량 증설**
