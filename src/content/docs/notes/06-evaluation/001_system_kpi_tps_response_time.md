## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **KPI(Key Performance Indicator)**: 목표 달성 여부를 판정하는 핵심 성과 지표이다.
- **SLI(Service Level Indicator)**: 서비스 수준을 직접 측정한 지표이다.
- **포화**: 부하가 늘어도 처리량이 증가하지 않는 상태이다.
- **꼬리 지연**: 일부 요청의 응답시간이 길어지는 현상이다.
- **중단**: 서비스를 정상 제공하지 못하는 구간이다.

</details>

- 정의/개념: 처리량•응답시간•가용성으로 목표를 판정하는 **성능 지표 체계**
- 배경/필요성: 평균값만으로는 부하 증가에 따른 **포화•꼬리 지연•중단** 을 구분하기 어려움

#### 한줄 요약

- 처리한 일의 양•기다린 시간•정상 제공 비율을 서로 다른 숫자로 확인함

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **처리량**: 단위 시간에 성공적으로 완료한 작업량이나 전송한 데이터량이다.
- **응답시간**: 요청을 보낸 시점부터 응답을 받을 때까지 걸린 시간이다.
- **백분위수(p95•p99)**: 요청의 95%•99%가 해당 값 이하에서 완료되는 꼬리 지연 지표이다.
- **관리 목표 체계**: 서비스 수준 지표•목표•협약을 연결해 측정값과 내부 목표, 외부 책임을 추적하는 구조이다.

</details>

- **측정 축**: 처리량•지연•오류의 다차원 성능 판단
- **분포 축**: 평균•p95•p99의 꼬리 지연 가시화
- **관리 축**: SLI•SLO•SLA의 목표•책임 추적

#### 한줄 요약

- 평균이 빨라도 일부 요청이 오래 기다리거나 실패하면 백분위수와 오류율에 드러남

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **TPS(Transactions Per Second)**: 1초에 성공적으로 완료한 업무 거래 수이다.
- **RPS(Requests Per Second)**: 1초에 처리한 개별 요청 수이다.
- **가용성**: 합의한 운영 시간 중 정상 서비스를 제공한 시간의 비율이다.
- **MTTR(Mean Time To Repair)**: 장애 뒤 정상 상태로 복구하는 평균 시간이다.

</details>

```text
                         [업무•측정 경계]
                                |
          +---------------------+---------------------+
          |                     |                     |
[처리량•성공•오류]   [평균•백분위 지연]   [가용성•복구시간]
          |                     |                     |
          +---------------------+---------------------+
                                |
                         [SLI•SLO•SLA]
```

선의 의미: 동일한 업무•측정 경계 안에서 처리량, 지연, 가용성 지표가 SLI•SLO•SLA 관리 체계와 결합되는 계층 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 업무•측정 경계 | **거래•요청•기간•성공** 정의 |
| 처리량•성공•오류 | **TPS•RPS•오류율** 집계 |
| 평균•백분위 지연 | **평균•p95•p99** 분포 |
| 가용성•복구시간 | **정상 시간•중단•MTTR** 집계 |
| SLI•SLO•SLA | **측정값•목표•계약 책임** 연결 |

#### 한줄 요약

- 같은 거래•기간•성공 기준으로 측정해야 지표를 서로 비교할 수 있음

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **측정 구간**: 지표의 시작•종료 시점과 집계 대상을 동일하게 정한 관측 범위이다.
- **성공 기준**: 오류나 취소를 제외하고 처리 완료로 인정할 요청•거래의 판정 규칙이다.
- **부하 조건**: 동시 사용자 수•요청률•업무 비율•지속시간으로 시험에서 재현할 작업량을 정한 기준이다.

</details>

```text
측정 책임자
     │ 1. 업무•부하•목표 정의
     │    거래•기간•성공•SLO 확정
     ▼
부하 발생기
     │ 2. 동시성•요청률 부하 생성
     │    시험 부하 조건 재현
     ▼
서비스
     │ 3. 완료•오류•구간 기록
     │    종료시각•상태•추적 수집
     ▼
수집•분석기
     │ 4. TPS•지연•가용성 산출
     │    분모•백분위•중단 계산
     ▼
SLO 충족•병목 판정
```

**동작 원리**

1. **업무•부하•목표 정의**: 거래•기간•성공•SLO 확정
2. **동시성•요청률 부하 생성**: 시험 부하 조건 재현
3. **완료•오류•구간 기록**: 종료시각•상태•추적 수집
4. **TPS•지연•가용성 산출**: 분모•백분위•중단 계산

#### 한줄 요약

- 요청 시작과 완료 기록을 짝지어 지연을 구하고 성공 건수를 시간 단위로 합침

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **업무 거래**: 사용자 관점에서 하나의 목적을 완료하는 여러 내부 요청의 묶음이다.
- **꼬리 지연**: 응답시간 분포에서 상위 백분위에 속하는 느린 요청의 지연이다.
- **처리량•응답시간•가용성 비교**: 각각 처리 용량•사용자 체감 속도•서비스 지속성을 판단하며 어느 하나가 다른 지표를 대신하지 못한다.

</details>

| 성능 지표 | 처리량 | 응답시간 | 가용성 |
|:---|:---|:---|:---|
| 적용 기준 | **업무 거래량** 확인 | **사용자 체감 속도** 측정 | **서비스 지속 여부** 측정 |
| 핵심 특징 | **완료 건수** 로 처리 용량 판단 | **요청 시간** 으로 지연 판단 | **정상 시간** 으로 지속성 판단 |
| 한계 | **실패 건수** 제외 | 평균의 **꼬리 지연 은폐** | 짧은 **측정 기간 왜곡** |

> 요약: **처리량•지연•가용성** 은 서로 다른 한계를 측정

#### 한줄 요약

- 처리량은 용량, 응답시간은 체감, 가용성은 지속성을 나타냄

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **SLO(Service Level Objective)**: SLI에 대해 내부적으로 달성할 목표값이다.
- **SLA(Service Level Agreement)**: 측정 기준•목표•책임을 합의한 계약이다.
- **오류율**: 전체 요청 중 실패로 판정한 요청이 차지하는 비율이다.
- **부하 대표성**: 피크 업무 비율•동시성•지속시간이 실제 운영 조건을 충분히 재현하는 정도이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거래•요청 경계 혼용으로 **TPS 과대 산정** | **업무 거래•성공•측정 기간** 을 고정하고 RPS와 분리 | 처리량의 **분모•업무 의미 일관성** 확보 |
| 평균 응답시간이 일부 장기 지연을 숨기는 **꼬리 지연 은폐** | 평균과 **p95•p99•오류율** 병행 측정 | 사용자 체감 저하와 포화 구간 식별 |
| 정상 부하만 측정해 피크 용량을 오판하는 **부하 대표성 부족** | **피크 업무 비율•동시성•지속시간** 재현 | 목표 SLO를 만족하는 **실제 처리 용량** 검증 |

#### 한줄 요약

- 출시 전 부하를 늘리며 TPS가 멈추고 p99가 급증하는 포화점을 찾음

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **다차원 성능 판단**: 처리량•지연•오류•가용성을 함께 보아 한 지표의 개선이 다른 지표를 악화시키는지 판정하는 방식이다.
- **용량 한계**: 부하 증가에도 처리량이 더 늘지 않고 지연과 오류가 급증하기 시작하는 경계이다.
- **지표 채택**: 업무 경계별 초당 트랜잭션 처리 건수•상위 99% 응답시간•가용성을 서비스 수준 목표의 측정 지표로 정하는 결정이다.

</details>

- 부하별 **TPS•p99** 와 가용성으로 SLO•증설 용량 결정

#### 한줄 요약

- 빠른 평균 하나가 아니라 용량•느린 요청•실패•중단을 함께 보고 규모를 결정함
