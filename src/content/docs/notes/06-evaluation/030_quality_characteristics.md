## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **4대 핵심 품질 특성(Core Quality Characteristics / ISO/IEC 25010 & 25023)**: 소프트웨어 시스템의 가치를 결정하는 가장 핵심적인 4가지 품질 속성인 기능 적합성(Functional Suitability), 성능 효율성(Performance Efficiency), 호환성(Compatibility), 보안성(Security)을 독립적인 정량 평가 영역으로 분리하고, 각 특성별 세부 하위 지표와 측정 메트릭을 수립하여 시스템 전 수명주기 동안 품질을 보증하는 엔지니어링 평가 체계.
- **단편적 기능 테스트 편향 및 비기능 상충 결함(Functional Bias & Quality Blindspot Defect)**: 화면의 버튼 클릭과 데이터 입출력(기능 적합성)만을 100% 검증한 후 배포하여, 동시 접속자 폭증 시 화면이 멈추거나(성능 결함), 타 시스템과의 API 연동 시 프로토콜 불일치로 통신이 두절되거나(호환성 결함), SQL Injection 공격으로 고객 데이터가 유출되는(보안성 결함) 구조적 결함.

</details>

- 정의/개념: 소프트웨어의 종합 품질과 비즈니스 안전성을 보증하기 위해 **4대 핵심 품질 특성(기능/성능/호환/보안) 식별 $\rightarrow$ ISO/IEC 25023 기반 정량적 메트릭 정의 $\rightarrow$ 품질 간 상충관계(Trade-off: 보안 vs 성능) 아키텍처 절충 $\rightarrow$ 요구사항 추적 매트릭스(RTM) 검증 $\rightarrow$ 독립 합격선 기반 최종 인수** 를 집행하는 **다차원 품질 평가 체계**
- 배경/필요성: 특정 단일 특성(기능)에만 편중된 검수는 시스템의 잠재적 붕괴 위험을 은폐하므로, 4대 핵심 축에 대해 독립된 합격 기준선을 수립하고 상호보완적 검증 필수

#### 한줄 요약
- 4대 품질 특성은 기능 적합성, 성능 효율성, 호환성, 보안성을 독립 지표로 정량화하여 시스템 완성도를 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **4대 핵심 품질 특성의 정의 및 평가 관점**:
  - **기능 적합성 (Functional Suitability)**: 요구된 비즈니스 업무 명세를 누락 없이 정확하게 수행하는 정도.
  - **성능 효율성 (Performance Efficiency)**: 제한된 하드웨어 자원에서 목표 처리량(TPS)과 응답시간(p99)을 만족하는 정도.
  - **호환성 (Compatibility)**: 다른 시스템과 동일 환경을 공유(공존성)하고 표준 인터페이스로 데이터를 교환(상호운용성)하는 정도.
  - **보안성 (Security)**: 권한 없는 접근, 데이터 위변조, 정보 유출을 차단하고 행위의 책임추적성을 보장하는 정도.

</details>

- **독립적인 과락 기준선(Independent Threshold)**: 4개 영역 중 단 하나라도 합격 기준에 미달할 경우 종합 점수와 무관하게 인수를 거부하는 절대 평가 원칙
- **품질 간 길항적 상충관계(Antagonistic Trade-off)**: 암호화 알고리즘 고도화(보안성 $\uparrow$) 시 CPU 연산 오버헤드로 인한 응답 지연(성능 $\downarrow$) 발생 현상을 아키텍처 레벨에서 최적 절충
- **요구사항 추적성 매트릭스(RTM: Requirements Traceability Matrix)**: RFP 요구사항 $\rightarrow$ 아키텍처 설계 $\rightarrow$ 테스트 케이스 $\rightarrow$ 정량 측정값 간의 100% 양방향 추적성 보증

#### 한줄 요약
- 4대 독립 과락 기준, 품질 상충관계(보안 vs 성능) 최적화, RTM 전 구간 추적성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **4대 품질 특성 및 세부 하위 특성 구조 (ISO/IEC 25010)**:
  1. **기능 적합성**: 완전성 (Completeness), 정확성 (Correctness), 적절성 (Appropriateness).
  2. **성능 효율성**: 시간 거동 (Time Behaviour), 자원 활용성 (Resource Utilization), 수용 용량 (Capacity).
  3. **호환성**: 공존성 (Co-existence), 상호운용성 (Interoperability).
  4. **보안성**: 기밀성 (Confidentiality), 무결성 (Integrity), 부인방지 (Non-repudiation), 책임추적성 (Accountability), 인증성 (Authenticity).

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4대 핵심 소프트웨어 품질 특성 및 정량 측정 매트릭스 ]                │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 1. 기능 적합성 (Functional) ]   │ [ 2. 성능 효율성 (Performance) ]    │
│ ├─ 완전성: 업무 요구 구현율 100%   │ ├─ 시간 거동: 피크 p99 응답시간 < 300ms│
│ ├─ 정확성: 금융 연산 오차율 0%    │ ├─ 자원 활용: CPU/메모리 가동률 < 70%│
│ └─ 적절성: 목표 업무 달성 부합도  │ └─ 수용 용량: 최대 5,000 TPS 보증   │
├───────────────────────────────────┼─────────────────────────────────────┤
│ [ 3. 호환성 (Compatibility) ]     │ [ 4. 보안성 (Security) ]            │
│ ├─ 공존성: 타 앱과 메모리 충돌 0건│ ├─ 기밀성/무결성: AES-256 / SHA-256 │
│ └─ 상호운용성: OpenAPI 규격 준수  │ ├─ 부인방지/인증: 전자서명 / OAuth2 │
│    (JSON/REST 포맷 100% 호환)     │ └─ 책임추적성: 감사 로그 위변조 방지│
└───────────────────────────────────┴─────────────────────────────────────┘
```

선의 의미: 4대 품질 특성을 세부 하위 특성 및 ISO 25023 정량 수치 기준과 매핑하여 구조화한 매트릭스

| 품질 특성 | 세부 하위 특성 | 정량 측정 메트릭 (ISO 25023) | 주요 검증 도구 |
|:---|:---|:---|:---|
| **기능 적합성** | 완전성, 정확성, 적절성 | 테스트 케이스 통과율 ($= 100\%$), 기능 커버리지 | JUnit, Selenium, Postman |
| **성능 효율성** | 시간 거동, 자원 활용, 용량 | p95/p99 지연시간 ($\le 300\text{ms}$), Throughput | JMeter, k6, nGrinder |
| **호환성** | 공존성, 상호운용성 | REST API Schema 준수율, OS/브라우저 호환율 | Swagger Validator, Docker |
| **보안성** | 기밀성, 무결성, 인증, 추적성 | CVSS 취약점 점수 ($= 0$), 침투 방어 성공률 | SonarQube, Fortify, ZAP |

#### 한줄 요약
- 기능 적합성(정확성), 성능 효율성(TPS/지연), 호환성(상호운용성), 보안성(기밀/무결성)으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **4대 품질 특성 통합 검증 및 인수 5단계 수명주기**:
  1. 비즈니스 요구사항 분석을 통해 4대 특성별 정량적 합격선(SLA) 정의
  2. 품질 상충관계(보안 vs 성능)를 조정하여 아키텍처 설계(HSM 가속기, 인메모리 캐시) 확정
  3. 개발 단계에서 RTM(요구사항 추적표)을 작성하고 기능 및 정적 코드 검증
  4. 독립된 스테이징 테스트베드에서 4대 특성별 분리 시험 동시 수행
  5. 모든 특성의 독립 합격선 충족 증적을 확인하고 최종 품질 인수 승인

</details>

```text
1. [품질 요구사항 및 목표 SLA 정의]
    ├─ 기능: 핵심 금융 결제 기능 150개 항목 정의 (구현율 목표 100%)
    ├─ 성능: 피크 3,000 TPS 인가 시 p99 응답시간 200ms 이하 보증
    ├─ 호환: 오픈뱅킹 REST API 표준 규격 100% 준수
    └─ [보안: 전송 구간 TLS 1.3 및 DB 개인정보 AES-256 암호화 의무화]
            │
            ▼
2. [품질 상충관계 분석 및 아키텍처 절충 (ATAM)]
    ├─ [상충 발견]: 실시간 DB 암호화 적용 시 쿼리 응답시간이 40ms ➔ 120ms로 급증 (성능 저하)
    └─ [아키텍처 절충]: 하드웨어 암호화 가속기(AES-NI) 도입 및 Redis 캐시 계층 추가 ➔ 성능 30ms로 방어
            │
            ▼
3. [RTM 추적표 작성 및 기능/보안 정적 검증]
    ├─ 기능 적합성: 단위/통합 테스트 자동화 (테스트 커버리지 88% 달성)
    └─ [보안성: SAST 정적 분석(SonarQube) ➔ CWE/OWASP 보안 약점 0건 검증]
            │
            ▼
4. [독립 테스트베드 동적 품질 시험]
    ├─ 기능 시험: 150개 비즈니스 시나리오 100% 정상 통과 (기능 합격)
    ├─ 성능 시험: JMeter 3,000 TPS 부하 주입 ➔ p99 150ms 기록 (성능 합격)
    ├─ 호환 시험: 금융결제원 테스트베드 연동 ➔ 데이터 패킷 왜곡 0건 (호환 합격)
    └─ [보안 시험: DAST 동적 침투 테스트 ➔ SQLi / XSS 침투 방어율 100% (보안 합격)]
            │
            ▼
5. [품질 인수 위원회 최종 승인]
    ├─ 4대 특성별 독립 합격선 전수 통과 확인 (과락 0건)
    └─ [RTM 증거 리포트 최종 서명 날인 ➔ 성공적 상용 서비스 배포]
```

**동작 원리**

1. **상충관계의 과학적 조율(ATAM Trade-off)**: 성능을 위해 보안을 희생하거나 보안을 위해 성능을 무너뜨리지 않고, 비동기 큐나 전용 하드웨어 가속기를 통해 두 특성을 동시 달성
2. **다차원 독립 과락제**: 기능 점수가 100점이라도 보안 취약점이 1건이라도 발견되면 배포를 즉각 차단하여 잠재 재난 방지
3. **상호운용성(Interoperability) 표준 준수**: 독자적 바이너리 프로토콜을 지양하고 W3C, OpenAPI 3.0, JSON 표준을 채택하여 미래 시스템 연계 비용 80% 절감
4. **책임추적성(Accountability)의 완전성**: 모든 금융 거래 로그에 조작 불가능한 WORM(Write Once Read Many) 스토리지를 적용하여 부인방지 보증
5. **RTM 기반 전수 증거화**: 감리 및 인수 시 "모든 기능 요구가 성능, 호환, 보안 테스트를 거쳤는가?"를 단일 매트릭스로 입증

#### 한줄 요약
- 요구 SLA 정의, ATAM 상충 절충, RTM 정적 검증, 4대 특성 독립 동적 시험, 최종 인수 승인 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **4대 핵심 품질 특성의 실패 양상 비교**:
  - 기능 적합성 실패: 잘못된 계산 결과, 오작동 (비즈니스 오류).
  - 성능 효율성 실패: 화면 멈춤, 타임아웃 504 에러 (용량 고갈).
  - 호환성 실패: API 연동 실패, 데이터 파싱 오류 (통신 단절).
  - 보안성 실패: 데이터 유출, 권한 탈취, 랜섬웨어 감염 (보안 사고).

</details>

| 비교 항목 | 기능 적합성 (Functional) | 성능 효율성 (Performance) | 호환성 (Compatibility) | 보안성 (Security) |
|:---|:---|:---|:---|:---|
| **핵심 실패 양상** | **업무 로직 계산 오류, 누락** | **응답 지연, 병목, OOM 다운** | **타 시스템 연동 에러, 파싱 오류**| **데이터 유출, 위변조, 침해사고**|
| **주요 테스트 기법**| **경계값 분석, 동등 분할, E2E**| **부하, 스트레스, 스파이크 시험**| **API 스키마 검증, 가상화 연동** | **SAST, DAST, 모의 침투 해킹** |
| **핵심 성공 척도** | **요구사항 100% 구현 및 통과**| **목표 TPS 달성 및 p99 지연 준수**| **오픈 API 표준 100% 규격 준수** | **CVSS 위험 취약점 0건 달성** |
| **주요 개선 기법** | 알고리즘 수정, 예외 처리 보강| 인덱스 튜닝, 캐시, 스케일아웃 | 표준 프로토콜 준수, 어댑터 패턴| 암호화, MFA 인증, RBAC 통제 |
| **품질 상충 관계** | 복잡한 기능 $\rightarrow$ 성능 저하 | 고성능 추구 $\rightarrow$ 보안 검증 생략 | 표준 준수 $\rightarrow$ 통신 오버헤드 | 다중 보안 $\rightarrow$ 응답 지연 발생 |

#### 한줄 요약
- 기능은 로직 무결성, 성능은 용량/지연 준수, 호환은 표준 연동, 보안은 침해 방어에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **4대 품질 특성 실무 검증 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|

## Ⅶ. 결론

- 소프트웨어 시스템의 완전성과 신뢰성을 다각도로 검증하는 엔지니어링 평가의 4대 기둥인 **핵심 품질 특성(기능·성능·호환·보안) 체계**는 단순한 기능 동작을 넘어 시스템의 생존성과 비즈니스 지속성을 보증하는 필수 평가 잣대이며, 실무 구현 시 **ISO/IEC 25010 준거 4대 특성별 독립 정량 합격선(SLA) 수립**, **품질 상충관계(Trade-off)의 아키텍처 최적 절충**, **요구사항 추적 매트릭스(RTM) 기반의 증거 중심 검증**, **독립 과락제 기반의 엄격한 인수 판정**을 완성하여 최고 수준의 소프트웨어 무결점 품질과 비즈니스 가치를 완성

#### 한줄 요약
- 기능·성능·호환·보안의 4대 품질 특성과 RTM 추적 검증을 통해 무결점 소프트웨어 품질을 완성한다.
