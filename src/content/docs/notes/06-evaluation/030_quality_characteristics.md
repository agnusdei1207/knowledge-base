## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **품질 특성**: 소프트웨어 품질을 독립적인 평가 관점으로 분류한 속성.
- **RTM**: 요구사항부터 설계·시험·결과까지 양방향으로 추적하는 매트릭스.

</details>

- 정의/개념: 기능·성능·호환·보안을 독립적으로 측정하는 **다차원 품질 체계**
- 배경/필요성: 소프트웨어 개발 시 기능 구현에만 매몰되어 비기능 핵심 품질 속성을 간과할 경우, 기능 테스트를 완벽히 통과했더라도 상용 부하 환경에서 응답 지연(성능 결함), 타 시스템 연동 실패(호환 결함), 또는 데이터 유출(보안 침해)과 같은 치명적 과락이 발생하여 대규모 아키텍처 재개발 비용이 초래되는 구조적 한계가 발생함에 따라, ISO/IEC 25010 표준에 기반하여 4대 핵심 품질 특성(기능 적합성, 성능 효율성, 호환성, 보안성)과 세부 하위 특성을 정의하고 상충관계(Trade-off)를 절충하는 다차원 품질 엔지니어링을 도입하여 **전 구간 요구사항 추적성 매트릭스(RTM) 확립, 특성별 독립 합격선 기반의 과락 방지 및 ATAM 기반 아키텍처 최적화**를 달성할 필요

#### 한줄 요약
- 4대 품질 특성은 기능·성능·호환·보안을 독립 기준으로 평가한다.

## Ⅱ. 특징

- 업무 요구의 완전·정확한 수행을 보는 **기능 적합성**
- 시간·자원·용량의 목표 달성을 보는 **성능 효율성**
- 공존과 정보 교환 능력을 보는 **호환성**
- 정보와 행위의 보호 능력을 보는 **보안성**
- 한 영역의 미달도 허용하지 않는 **독립 과락 기준**
- 특성 간 충돌을 조정하는 **품질 트레이드오프**
- 요구부터 시험 결과까지 연결하는 **RTM 추적성**

#### 한줄 요약
- 독립 과락, 특성 간 상충 조정, RTM 추적성이 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── 4대 핵심 품질 특성 ──────────────┐
│                                                │
├── [기능 적합성]                                │
│   └── 완전성 · 정확성 · 적절성                 │
├── [성능 효율성]                                │
│   └── 시간 거동 · 자원 활용성 · 용량           │
├── [호환성]                                     │
│   └── 공존성 · 상호운용성                      │
└── [보안성]                                     │
    └── 기밀성 · 무결성 · 인증성 · 책임추적성    │
```

| 구성요소 | 책임 |
|:---|:---|
| **기능 적합성** | 기능 완전성·정확성·적절성 평가 |
| **성능 효율성** | 시간 거동·자원 활용·용량 평가 |
| **호환성** | 공존성과 상호운용성 평가 |
| **보안성** | 기밀성·무결성·인증성 평가 |

#### 한줄 요약
- 네 특성은 각자 고유 하위 특성으로 측정되므로 한 특성의 초과 달성이 다른 특성의 미달을 상쇄하지 못하고, 성능 효율성과 보안성처럼 서로 자원을 다투는 축은 설계 단계에서 절충하지 않으면 인수 시험에서 과락으로 되돌아온다.

## Ⅳ. 흐름도

```text
[사업 요구]
     │
     │ 1. 특성별 품질 목표 정의
     ▼
[품질 관리자]
     │ 2. 상충관계 분석과 설계 절충
     │ 3. RTM 추적 관계 수립
     │ 4. 특성별 독립 시험
     │ 5. 과락 여부와 증거 판정
     ▼
[인수 책임자]
     │
     └──────── 인수 결과 반환
```

**동작 원리**

1. **특성별 품질 목표 정의**: 지표·측정 조건·합격선 명세
2. **상충관계 분석과 설계 절충**: 시나리오별 민감점과 대안 평가
3. **RTM 추적 관계 수립**: 요구·설계·시험·결과의 양방향 연결
4. **특성별 독립 시험**: 기능·부하·연동·보안 시험 수행
5. **과락 여부와 증거 판정**: 모든 독립 합격선의 충족 확인

#### 한줄 요약
- 상충관계 분석과 RTM 수립을 시험 앞에 두느냐가 갈림길이며, 이를 건너뛰면 특성별 독립 시험에서야 절충 실패가 드러나 설계 변경 비용을 인수 직전에 치르게 된다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 기능 적합성 | 성능 효율성 | 호환성 | 보안성 |
|:---|:---|:---|:---|:---|
| 실패 양상 | **업무 오류** | **응답 지연** | **연동 실패** | **정보 침해** |
| 대표 지표 | 기능 구현률 | p99·TPS | 규격 준수율 | 취약점 등급 |
| 검증 방식 | 기능·경계값 시험 | 부하·스트레스 시험 | 스키마·연동 시험 | SAST·DAST·침투 시험 |
| 개선 방향 | 로직·예외 처리 보강 | 캐시·튜닝·확장 | 표준·어댑터 적용 | 암호화·인증·권한 통제 |

#### 한줄 요약
- 기능은 정확성, 성능은 지연·용량, 호환은 연동, 보안은 보호를 평가한다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| 기능 시험 편중으로 성능 병목 누락 | 운영 조건의 **부하 시험** 수행 |
| 보안 강화로 응답 지연 증가 | ATAM 기반 **상충관계 절충** |
| 독자 규격으로 연동 장애 발생 | OpenAPI 등 **표준 인터페이스** 채택 |
| 요구와 시험 결과의 연결 단절 | 전 구간 **RTM 추적성** 유지 |
| 종합 점수로 취약 영역 은폐 | 특성별 **독립 합격선** 적용 |

#### 한줄 요약
- 부하 시험, 상충 절충, 표준 연동, RTM, 독립 과락으로 품질을 통제한다.

## Ⅶ. 결론

- 소프트웨어의 성공적 운영을 결정짓는 핵심 품질 축들을 독립적으로 정량 측정하고 상충하는 설계 속성을 과학적으로 절충하는 **소프트웨어 핵심 품질 속성 및 상충관계 최적화(4 Core Quality Characteristics / Functionality·Performance·Compatibility·Security / ISO 25023 & ATAM)의 필수 평가 표준**으로 확고히 자리 잡았으며, 데브섹옵스(DevSecOps) 및 자동화된 품질 게이트(Quality Gate) 파이프라인으로 진화하는 가운데, 실무 소프트웨어 인수 및 아키텍처 평가 시에는 **어느 한 특성의 우수함으로 타 특성의 미달을 상쇄하지 못하도록 하는 특성별 독립 과락 기준 적용, 암호화와 응답 지연 간의 상충관계를 사전에 조율하는 ATAM 평가, 요구사항부터 테스트 결과까지 양방향 추적성을 보증하는 RTM의 상시 최신화**를 결합하여 완벽한 고품질 소프트웨어를 완성

#### 한줄 요약
- 4대 핵심 품질 특성의 독립 합격선과 상충관계 절충을 통해 균형 잡힌 고품질 시스템을 완성한다.
