## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 모델링(Performance Modeling / Capacity Planning & Architecture Evaluation)**: 시스템을 실제로 구현하거나 대규모 하드웨어를 구매하기 전에, 소프트웨어 컴포넌트의 동작 구조, 자원 요구량, 트래픽 워크로드를 수학적 수식(분석적 모델) 또는 컴퓨터 시뮬레이션(이산 사건 시뮬레이션)으로 추상화하여, 다양한 아키텍처 설계 대안별 처리량(TPS), 응답시간(Latency), 자원 가동률, 병목 지점을 정량적으로 사전 예측하는 성능 엔지니어링 기법.
- **사후 병목 발견에 따른 아키텍처 전면 재작성 결함(Post-deployment Redesign Defect)**: 시스템 구축 완료 후 상용 배포 단계에서 뒤늦게 구조적 락(Lock) 경합이나 대역폭 병목에 의한 SLA 위반을 발견하여, 하드웨어 증설로도 해결되지 않아 전체 시스템 아키텍처를 수십억 원을 들여 재설계해야 하는 구조적 결함.

</details>

- 정의/개념: 아키텍처 설계 단계에서 성능 리스크를 선제 제거하기 위해 **워크로드 프로파일링 $\rightarrow$ 분석적 큐잉 네트워크(QN/LQN) 또는 이산 사건 시뮬레이션(DES) 모델 구축 $\rightarrow$ 실측치 기반 모형 보정(Model Calibration) $\rightarrow$ 가상 부하 시나리오별 대안 성능 예측 $\rightarrow$ 민감도 분석(Sensitivity Analysis) 기반 최적 아키텍처 및 자원 스펙 확정** 을 집행하는 **선제적 성능 예측 공학 체계**
- 배경/필요성: 분산 자원 경합 증가로 직관적 **용량 산정** 한계

#### 한줄 요약
- 성능 모델링은 큐잉 네트워크와 시뮬레이션을 통해 시스템 구축 전 처리량과 지연시간을 수학적으로 예측한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **성능 모델링 2대 핵심 접근 방식**:
  - **분석적 모델 (Analytical Models)**: 큐잉 이론(MVA, 잭슨 네트워크)을 기반으로 폐쇄형/개방형 수식을 통해 평균 성능 상태를 1초 내에 신속 계산.
  - **시뮬레이션 모델 (Simulation Models)**: 이산 사건 시뮬레이션(DES)을 통해 시간의 흐름에 따른 큐의 동적 변화, 버스트 트래픽, 분기 조건을 정밀 모사.

</details>

- 구현 전에 확장 한계와 병목을 찾는 **사전 검증성**
- 자원 변경 효과를 비교하는 **What-If 분석**
- 소프트웨어·하드웨어 경합을 표현하는 **LQN**

#### 한줄 요약
- 사전 병목 검증, What-If 시나리오 분석, 계층형 큐잉 모델(LQN), 분석/시뮬레이션 상호보완을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성능 모델링 4대 핵심 아키텍처 컴포넌트**:
  1. **Workload Model (부하 모델)**: 트랜잭션 종류별 도착률($\lambda$), 사용자 생각시간($Z$), 트랜잭션 믹스(Mix).
  2. **Software Contention Model (LQN)**: 프로세스, 스레드 풀, DB Lock, 세마포어 등 논리적 자원 모델.
  3. **Hardware Platform Model**: CPU 코어, 메모리 대역폭, 스토리지 IOPS, 네트워크 레이턴시.
  4. **Solver & Calibration Engine**: MVA 수식 풀이 엔진, 이산 사건 시뮬레이터, 오차 보정기.

</details>

```text
성능 모델링 체계
├─ Workload Model
├─ Software Contention Model
├─ Hardware Platform Model
└─ Solver·Calibration Engine
```

선의 의미: 워크로드와 플랫폼 파라미터를 입력받아 계층형 큐잉 모델(LQN)로 추상화하고 MVA 엔진으로 해석하여 병목과 성능을 도출하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **Workload Model** | 도착률·생각시간·트랜잭션 믹스 정의 |
| **Software Contention Model** | 스레드·연결 풀·락의 논리 경합 표현 |
| **Hardware Platform Model** | CPU·메모리·IOPS·네트워크 자원 표현 |
| **Solver·Calibration Engine** | MVA·DES 해석과 실측 오차 보정 |

#### 한줄 요약
- 워크로드 모델, LQN 계층형 모델, MVA 분석적 솔버, 이산 사건 시뮬레이터, 민감도 분석기로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **성능 모델링 및 아키텍처 평가 5단계 엔지니어링 프로세스**:
  1. 목표 비즈니스 요구사항 및 시스템 아키텍처 블록 다이어그램 분석
  2. 소프트웨어 컴포넌트별 소요 시간($t_{service}$) 및 워크로드 파라미터 도출
  3. LQN 계층형 큐잉 모델 구축 및 MVA 수식 해석을 통한 초기 성능 예측
  4. 핵심 프로토타입 실측 데이터와 대조하여 모델 변수 보정(Model Calibration)
  5. 다양한 아키텍처 대안(캐시 도입, DB 샤딩)에 대한 What-If 시뮬레이션 및 최적안 확정

</details>

```text
1. [아키텍처 및 요구사항 분석]
    ├─ 대상: 글로벌 이커머스 마이크로서비스 아키텍처
    └─ [요구 목표: 피크 시 10,000 TPS 수용 및 평균 응답시간 100ms 이하 보증]
            │
            ▼
2. [컴포넌트 원단위 계측 및 워크로드 정의]
    ├─ Web 요청 처리: 2ms (CPU), WAS 주문 비즈니스 로직: 15ms (CPU)
    ├─ DB 쿼리 실행: 8ms (Disk I/O), 외부 결제 PG 연계: 50ms (Network RTT)
    └─ [트랜잭션 믹스: 상품 조회(85%), 결제 주문(15%)]
            │
            ▼
3. [LQN 모델 구축 및 MVA 해석 실행]
    ├─ 계층형 큐잉 네트워크(LQN) 도면 작성 ➔ MVA 솔버 구동
    ├─ [1차 예측 결과] 최대 처리량: 6,200 TPS에서 정체, 평균 응답시간 380ms
    └─ [병목 원인 식별: 외부 결제 PG의 50ms 동기 블로킹으로 인한 WAS 스레드 고갈]
            │
            ▼
4. [What-If 아키텍처 개선안 시뮬레이션]
    ├─ [개선안 A: 단순 서버 Scale-up] ➔ 코어 2배 증설 시 처리량 6,500 TPS (개선율 4.8%, 효과 미미)
    ├─ [개선안 B: 비동기 메시지 큐(Kafka) 전환] ➔ 주문 요청 즉시 반환(3ms), 결제 비동기 분리
    └─ [개선안 B 해석 결과: 12,500 TPS 달성 및 응답시간 25ms 기록 ➔ 목표 100% 초과 달성]
            │
            ▼
5. [모형 보정 및 최종 아키텍처 승인]
    ├─ PoC 프로토타입 실측치와 모델 예측치 오차 4.2% 검증 (높은 신뢰도 확정)
    └─ [Kafka 기반 비동기 아키텍처 확정 및 인프라 하드웨어 구매 발주 승인]
```

**동작 원리**

1. **아키텍처 및 요구사항 분석**: 목표 처리량·응답시간 확정
2. **컴포넌트 원단위 계측 및 워크로드 정의**: 입력값 산출
3. **LQN 모델 구축 및 MVA 해석 실행**: 병목과 성능 예측
4. **What-If 아키텍처 개선안 시뮬레이션**: 대안별 효과 비교
5. **모형 보정 및 최종 아키텍처 승인**: 실측 오차 확인

#### 한줄 요약
- 요구사항 분석, 컴포넌트 원단위 계측, LQN/MVA 해석, What-If 대안 시뮬레이션, 모형 보정 및 확정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **성능 모델링 2대 접근 방식 비교**:
  - 분석적 모델 (Analytical Model: QN, MVA, LQN): 수식 기반 (초고속, 평균 상태 중심).
  - 시뮬레이션 모델 (Simulation Model: DES, Petri-Net): 사건 기반 모사 (정밀, 롱테일 및 동적 상태 중심).

</details>

| 비교 항목 | 분석적 모델 (Analytical Models) | 시뮬레이션 모델 (Simulation Models) |
|:---|:---|:---|
| **핵심 기법** | **큐잉 네트워크 (QN), MVA, LQN** | **이산 사건 시뮬레이션 (DES), 페트리넷** |
| **모델 구축 비용**| **낮음 (수식 및 블록 다이어그램 기반)** | 높음 (전용 시뮬레이션 코드 작성 필요)|
| **연산 실행 시간**| **초 단위 (즉각적인 실시간 해석)** | 수 분 ~ 수 시간 (대량 이벤트 실행 필요)|
| **정밀도 및 범위**| **평균값(Mean) 중심 해석, 분포 단순화** | **백분위수(p99) 및 버스트 트래픽 정밀 모사**|
| **장점** | 수백 개 설계 대안의 신속한 스크리닝 | 복잡한 비선형 로직 및 과도 상태(Transient) 분석|
| **단점** | 복잡한 조건 분기 및 롱테일 반영 한계 | 모델 구축 오버헤드 및 디버깅 복잡성 |
| **실무 적용 단계**| **초기 아키텍처 설계 및 대안 비교 단계**| **최종 아키텍처 상세 검증 및 극한 내구 분석**|

#### 한줄 요약
- 분석적 모델은 초기 빠른 대안 스크리닝에, 시뮬레이션 모델은 복잡한 동적 롱테일 정밀 검증에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **성능 모델링 실무 적용 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모델 연산을 단순화하기 위해 지수 분포(Exponential)를 가정한 결과 **실제 트래픽의 버스트 및 롱테일(Heavy-tail) 지연을 예측하지 못하는 모델 오류 발생** | **초기에는 MVA 분석 모델을 사용하고, 상세 검증 시 실제 트래픽 로그를 재생하는 이산 사건 시뮬레이션(DES)을 병행 적용** | 롱테일 지연 및 버스트 트래픽 예측 정확도 95% 확보 |
| 모델에 입력된 소프트웨어 컴포넌트의 서비스 시간($t_{service}$)이 부정확하여 **시뮬레이션 결과와 실제 시스템 성능 간에 50% 이상의 큰 오차 발생** | **핵심 비즈니스 로직에 대해 1코어 단위의 프로토타입 마이크로 벤치마크를 수행하여 실측 파라미터로 모델을 정밀 보정(Calibration)** | 모델 예측 오차 5% 이내로 극소화 |
| 소프트웨어 스레드 풀이나 커넥션 풀을 무시하고 하드웨어 자원만 모델링하여 **CPU는 20%인데 스레드 고갈로 시스템이 멈추는 소프트웨어 병목 누락** | **소프트웨어 자원과 하드웨어 자원의 다계층 호출 관계를 지원하는 계층형 큐잉 모델(LQN: Layered Queueing Networks) 강제** | 소프트웨어 스레드/락 병목 사전 완벽 식별 |

#### 한줄 요약
- DES 병행으로 롱테일을 잡고, 프로토타입 실측으로 보정하며, LQN으로 소프트웨어 병목을 식별한다.

## Ⅶ. 결론

- 평균 대안은 **MVA**, 버스트·롱테일은 **DES**로 검증해 용량 결정

#### 한줄 요약
- LQN 큐잉 모델과 MVA/DES 융합을 통해 구축 전 무결점 아키텍처 성능을 완성한다.
