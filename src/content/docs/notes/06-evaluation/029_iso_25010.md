## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISO/IEC 25010 (SQuaRE 제품 품질 모델 / Systems and software Quality Requirements and Evaluation)**: 소프트웨어 시스템 및 ICT 융합 제품의 품질을 체계적으로 명세, 측정, 평가하기 위해 국제표준화기구(ISO)에서 제정한 제품 품질 표준 체계로, 기능 적합성, 성능 효율성, 호환성, 상호작용 역량, 신뢰성, 보안성, 유지보수성, 유연성, 안전성(2023판 기준 9대 특성)의 상위 품질 특성과 세부 하위 특성을 계층적으로 정의한 국제 표준 프레임워크.
- **모호한 비기능 요구사항 명세 및 인수 분쟁 결함(Vague Non-Functional Requirement Defect)**: 제안요청서(RFP)나 계약서에 "시스템은 안전하고 빨라야 한다"와 같이 주관적이고 정성적인 표현만 기술하여, 개발 완료 후 발주사와 수주사 간에 성능 지연, 보안 취약점, 유지보수 불가 문제를 두고 법적 소송 및 인수 거부가 발생하는 구조적 결함.

</details>

- 정의/개념: 소프트웨어 제품의 품질 무결성과 객관적 인수 기준을 확립하기 위해 **비즈니스 도메인 위험 분석 $\rightarrow$ ISO/IEC 25010 9대 품질 특성 및 하위 특성 매핑 $\rightarrow$ ISO/IEC 25023 기반 정량적 측정 메트릭(SLA/SLO) 정의 $\rightarrow$ 테스트베드 실측 검증 $\rightarrow$ 정량적 데이터 기반 인수(Acceptance) 판정** 을 집행하는 **국제 표준 품질 거버넌스 체계**
- 배경/필요성: 클라우드 네이티브, AI 시스템, 자율주행 등 복합 임베디드 소프트웨어의 확산에 따라 인명 안전(Safety)과 이기종 연동(Flexibility)을 포괄하는 고도화된 품질 평가 모델 요구

#### 한줄 요약
- ISO/IEC 25010은 소프트웨어 제품의 9대 품질 특성을 정의하여 정량적 요구사항 명세와 객관적 인수 검증을 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ISO/IEC 25010 2023 개정판 3대 주요 혁신점**:
  - **안전성(Safety) 특성 신설**: 시스템이 인명, 재산, 환경에 위해를 가하지 않음을 보증하는 독립 상위 특성 추가.
  - **상호작용 역량(Interaction Capability)**: 기존 사용성(Usability)을 인간-기계 인터랙션 및 접근성 중심으로 명칭 및 범위 확장.
  - **유연성(Flexibility)**: 기존 이식성(Portability)을 클라우드/AI 등 환경 변화에 대한 적응성(Adaptability) 중심으로 확장.

</details>

- **SQuaRE (ISO/IEC 25000 시리즈) 패밀리의 핵심 참조 모델**: 2501n(품질 모델), 2502n(품질 측정), 2503n(품질 요구사항), 2504n(품질 평가)을 관통하는 중심 축
- **2대 품질 모델의 상호 연계**: 시스템 자체의 정적/동적 속성을 평가하는 **제품 품질 모델(Product Quality)** 과 최종 사용자가 업무를 완수하는 경험을 평가하는 **사용 품질 모델(Quality in Use)** 의 이원화
- **품질 상충관계(Quality Trade-off)의 체계적 절충**: 강력한 암호화(보안성 증대)로 인한 응답 지연(성능 효율성 감소)과 같은 아키텍처 상충관계를 정량적 메트릭으로 시각화 및 최적화

#### 한줄 요약
- 2023판 9대 품질 특성 체계, SQuaRE 시리즈 연계, 제품 품질과 사용 품질의 이원화, 품질 상충관계 조율을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ISO/IEC 25010:2023 9대 제품 품질 특성 및 세부 하위 특성**:
  1. **기능 적합성 (Functional Suitability)**: 완전성, 정확성, 적절성.
  2. **성능 효율성 (Performance Efficiency)**: 시간 거동(응답시간), 자원 활용성, 수용 용량.
  3. **호환성 (Compatibility)**: 공존성, 상호운용성.
  4. **상호작용 역량 (Interaction Capability)**: 적합성 인지성, 학습성, 운영성, 사용자 오류 방지성, UI 매력성, 접근성.
  5. **신뢰성 (Reliability)**: 무결함성, 가용성, 내결함성, 회복성.
  6. **보안성 (Security)**: 기밀성, 무결성, 부인방지성, 책임추적성, 인증성.
  7. **유지보수성 (Maintainability)**: 모듈성, 재사용성, 분석성, 수정성, 시험성.
  8. **유연성 (Flexibility)**: 적응성, 확장성, 설치성, 대체성.
  9. **안전성 (Safety)**: 운영 안전성, 위험 식별성, 안전 보증성.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ ISO/IEC 25010:2023 제품 품질 모델 9대 상위 특성 매트릭스 ]            │

│ 1. 기능 적합성    │ 2. 성능 효율성    │ 3. 호환성                       │

│ └─ 기능 적절성    │ └─ 수용 용량(Max) │                                 │
├───────────────────┼───────────────────┼─────────────────────────────────┤
│ 4. 상호작용 역량  │ 5. 신뢰성         │ 6. 보안성                       │
│ ├─ 학습성/운영성  │ ├─ 가용성 (99.99%)│ ├─ 기밀성 / 무결성              │
│ ├─ 오류 방지성    │ ├─ 내결함성 (FTS) │ ├─ 부인방지 / 인증성            │
│ └─ 접근성 (Web/앱)│ └─ 회복성 (MTTR)  │ └─ 책임추적성 (Audit Log)       │
├───────────────────┼───────────────────┼─────────────────────────────────┤
│ 7. 유지보수성     │ 8. 유연성         │ 9. 안전성 (2023 신설)           │
│ ├─ 모듈성/재사용성│ ├─ 적응성 (Multi) │ ├─ 운영 안전성 (Fail-Safe)      │
│ ├─ 수정성/분석성  │ ├─ 확장성 (Scale) │ ├─ 위험 식별성 (Risk Detection) │
│ └─ 시험성 (Test)  │ └─ 대체성/설치성  │ └─ 안전 보증성 (Safety Assurance)│
└───────────────────┴───────────────────┴─────────────────────────────────┘
```

선의 의미: 9개 최상위 품질 특성과 각각의 세부 하위 특성으로 소프트웨어 전 영역을 구조화한 매트릭스

| 품질 특성 (2023) | 물리적 정의 | 핵심 측정 메트릭 (ISO 25023) | 비고 |
|:---|:---|:---|:---|
| **기능 적합성** | 요구된 기능을 정확하고 빠짐없이 수행하는 정도 | 기능 구현율(%), 계산 오차율(%) | Functional |
| **성능 효율성** | 자원 사용 대비 응답 속도 및 처리 용량 | p99 레이턴시(ms), 초당 TPS, CPU 가동률 | Performance |
| **호환성** | 이기종 타 시스템과 정보 및 자원을 원활히 공유 | API 규격 준수율, 동시 구동 오류율 | Interface |
| **상호작용 역량** | 사용자가 직관적이고 오류 없이 만족스럽게 사용 | 태스크 완수 시간(초), UI 오류율 | Usability |
| **신뢰성** | 규정된 조건에서 장애 없이 무중단 기능을 유지 | MTBF(시간), MTTR(분), 가용성(%) | Reliability |
| **보안성** | 비인가 접근, 위변조, 정보 유출을 완벽히 방어 | 취약점 제로(CVSS), 침투 방어율(%) | Security |
| **유지보수성** | 결함 수정, 리팩토링, 단위 테스트 작성이 쉬운 정도| 순환 복잡도, 코드 커버리지(%) | Maintain |
| **유연성** | 클라우드, OS, 디바이스 등 다양한 환경 적응성 | 이식 소요 공수(MM), 컨테이너 호환성 | Flexibility |
| **안전성** | 오작동 시에도 인명 및 재산에 피해를 주지 않는 정도| SIL 등급 준수율, 비상 정지 성공률 | **2023 신설** |

#### 한줄 요약
- 9대 특성(기능 적합성, 성능, 호환성, 상호작용, 신뢰성, 보안성, 유지보수성, 유연성, 안전성)과 세부 메트릭으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ISO/IEC 25010 기반 정량 품질 관리 5단계 수명주기**:
  1. 프로젝트 착수 시 도메인 특성에 따른 9대 품질 특성 가중치(RFP) 확정
  2. ISO/IEC 25023 표준 메트릭을 기반으로 정량적 SLO 목표치 수치화
  3. 아키텍처 설계 및 구현 단계에서 정적 분석(유지보수성) 및 보안 검증 수행
  4. 테스트베드에서 기능, 부하(성능), 침투(보안), 카오스(신뢰성) 종합 시험
  5. 정량 메트릭 달성률 증거(Report)를 대조하여 최종 고객 인수 판정 집행

</details>

```text
1. [품질 요구사항 정의 (RFP 명세화)]
    ├─ 도메인: 차세대 인터넷 뱅킹 코어 시스템
    ├─ 중점 품질 특성: 성능 효율성(25%), 보안성(30%), 신뢰성(25%), 기능 적합성(20%)
    └─ [선언적 표현 금지 ➔ ISO 25010 특성별 정량 수치(SLA) 명세화]
            │
            ▼
2. [ISO/IEC 25023 정량 메트릭 매핑]
    ├─ 성능: "피크 5,000 TPS에서 p99 응답시간 $\le 300\text{ms}$, CPU 가동률 $\le 70\%$"
    ├─ 신뢰성: "연간 가용성 $\ge 99.99\%$, 페일오버 시간 $\le 5\text{초}$"
    └─ [보안성: "OWASP Top 10 취약점 0건, 모든 금융 데이터 AES-256 GCM 암호화"]
            │
            ▼
3. [설계 및 정적/동적 검증 집행]
    ├─ 유지보수성 검증: SonarQube 정적 분석 (순환 복잡도 $\le 10$, 단위 테스트 커버리지 $\ge 85\%$)
    └─ [안전성 검증: Fail-Safe 비상 차단 모듈 락스텝 아키텍처 설계]
            │
            ▼
4. [공인 BMT 및 품질 시험 평가]
    ├─ JMeter 분산 부하 테스트 ➔ 5,200 TPS에서 p99 180ms 기록 (성능 합격)
    ├─ 모의 해킹 및 취약점 스캐닝 ➔ High/Medium 취약점 0건 검증 (보안 합격)
    └─ [Chaos Mesh 장애 주입 ➔ Multi-AZ 자동 페일오버 3.5초 기록 (신뢰성 합격)]
            │
            ▼
5. [품질 인수 및 잔여 위험 공식 승인]
    ├─ 9대 품질 특성별 검증 리포트 종합 (달성률 100%)
    └─ [발주사 인수 위원회 최종 서명 날인 ➔ 시스템 성공적 상용 오픈]
```

**동작 원리**

1. **품질의 정량화(Quantification)**: "쓰기 편해야 한다"는 정성적 요구를 "초보 사용자의 1회 계좌 이체 완수 시간 30초 이내"라는 측정 가능한 수치로 변환
2. **품질 속성 간 상충관계 최적화**: ATAM(Architecture Tradeoff Analysis Method)을 적용하여 보안성 강화 시 발생하는 지연시간을 비동기 하드웨어 가속기(HSM)로 상쇄
3. **전 수명주기 품질 추적성(Traceability)**: 요구사항 정의서(RFP) $\rightarrow$ 아키텍처 설계서 $\rightarrow$ 테스트 케이스 $\rightarrow$ BMT 실측 결과서가 1:1로 상호 매핑
4. **사용 품질(Quality in Use)과의 연계**: 제품 내부 품질이 우수하더라도 실제 업무 환경에서 사용자의 효과성(Effectiveness), 효율성(Efficiency), 만족도(Satisfaction)를 RUM(Real User Monitoring)으로 최종 검증
5. **국제 표준 계약 분쟁 방어**: ISO/IEC 25010 및 25023을 계약서 표준 규격으로 채택하여 하자보수 범위 및 완료 기준을 법적으로 명확화

#### 한줄 요약
- RFP 요구 명세, ISO 25023 정량 메트릭 매핑, 정적/동적 검증, 종합 BMT 시험, 정량적 인수 승인 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ISO/IEC 25010 판본별 8대 특성 vs 9대 특성 비교**:
  - 2011년 구판 (8대 특성): Functional Suitability, Performance, Compatibility, Usability, Reliability, Security, Maintainability, Portability.
  - 2023년 최신판 (9대 특성): Usability $\rightarrow$ **Interaction Capability** 개편, Portability $\rightarrow$ **Flexibility** 확장, **Safety** 신설.

</details>

| 비교 항목 | ISO/IEC 25010:2011 (구판 8대 특성) | ISO/IEC 25010:2023 (최신판 9대 특성) |
|:---|:---|:---|
| **총 품질 특성 수** | **8개 특성 (31개 하위 특성)** | **9개 특성 (새로운 하위 특성 체계)** |
| **안전성 (Safety)** | 신뢰성 또는 사용성의 하위 개념으로 간주 | **독립된 9번째 상위 특성으로 전격 신설** |
| **사용성 (Usability)**| Usability (단순 조작 편의성 중심) | **Interaction Capability (인터랙션 및 접근성)**|
| **이식성 (Portability)**| Portability (OS 환경 간 단순 이전) | **Flexibility (클라우드/AI 등 환경 적응성)**|
| **현대 IT 기술 반영**| 레거시 온프레미스 클라이언트/서버 중심 | **클라우드, 마이크로서비스, AI/ML, 임베디드**|
| **실무 적용 권고** | 기존 운영 중인 유지보수 계약 참조 | **모든 신규 차세대 정보시스템 구축 표준** |

#### 한줄 요약
- 2011판은 8대 특성(이식성/사용성 중심), 2023판은 안전성(Safety) 신설 및 인터랙션/유연성을 강화한 9대 특성이다.

## Ⅶ. 결론

- 소프트웨어 공학의 모든 비기능 품질 속성을 정량적이고 체계적인 엔지니어링 체계로 승화시키는 글로벌 최고 표준인 **ISO/IEC 25010 체계**는 개발자와 발주자 간의 의사소통 장벽을 허물고 시스템의 완성도를 입증하는 객관적 나침반이며, 실무 구현 시 **2023년 개정판 9대 품질 특성(Safety 신설)의 전수 반영**, **ISO/IEC 25023 연계 정량 측정 메트릭 수립**, **품질 상충관계(Trade-off) 아키텍처 최적화**, **제품 품질과 사용 품질(Quality in Use)의 동시 검증**을 완성하여 최고 수준의 소프트웨어 경쟁력과 무결점 제품 가치를 완성
