## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **고장 모드 및 영향 분석(FMEA: Failure Mode and Effects Analysis / IEC 60812 & AIAG-VDA)**: 시스템, 하드웨어 부품, 소프트웨어 모듈, 또는 운영 프로세스의 가장 기초적인 단위에서 발생할 수 있는 모든 잠재적 고장 형태(Failure Mode)를 전수 식별하고, 각 고장이 상위 시스템과 최종 사용자에게 미치는 영향(Effects), 근본 원인(Causes), 그리고 현재의 예방/검출 통제 수단을 분석하여, 심각도(Severity, S), 발생도(Occurrence, O), 검출도(Detection, D)의 3차원 척도로 위험우선순위(RPN = $S \times O \times D$) 및 조치 우선순위(AP: Action Priority)를 산출하는 상향식(Bottom-up) 귀납적 신뢰성 분석 기법.
- **사후 장애 수습 편향 및 RPN 곱셈 왜곡 결함(RPN Multiplication Trap Defect)**: 장애가 터진 후에야 원인을 찾는 늑장 대응에 머무르거나, 단순 곱셈 방식($RPN = S \times O \times D$)에 의존하여 심각도가 극도로 높은 치명적 결함($S=10$, 인명 피해/전면 다운)임에도 발생 빈도가 낮다는($O=1, D=2 \rightarrow RPN=20$) 이유로 개선 조치 대상에서 누락시키는 구조적 결함.

</details>

- 정의/개념: 개발 초기 단계에서 잠재 결함을 선제적으로 박멸하기 위해 **기능 요구사항 정의 $\rightarrow$ 잠재 고장 모드 및 상위 영향 분석 $\rightarrow$ 심각도(S)$\cdot$발생도(O)$\cdot$검출도(D) 정량 평가 $\rightarrow$ AIAG-VDA 조치 우선순위(AP: High/Medium/Low) 판정 $\rightarrow$ 설계 개선 및 검출 통제 강화 후 재평가** 를 집행하는 **선제적 신뢰성 예방 공학 체계**
- 배경/필요성: 소프트웨어 배포 후 운영 환경에서 결함을 수정하는 비용은 설계 단계에서 FMEA로 예방하는 비용의 100배 이상에 달하므로, 개발 라이프사이클의 가장 앞단(Shift-Left)에서 전수 위험 평가 필수

#### 한줄 요약
- FMEA는 단위 컴포넌트의 잠재 고장 모드를 상향식으로 분석하고 S/O/D 지수를 평가하여 설계 개선을 선제 집행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **FMEA 3대 핵심 평가 척도 (1~10점 척도)**:
  - **심각도 ($S$, Severity)**: 해당 고장 모드가 사용자 및 전체 시스템에 미치는 피해의 치명도 ($10$: 치명적 인명/전면 마비 $\sim 1$: 체감 불가).
  - **발생도 ($O$, Occurrence)**: 해당 고장 원인이 실제로 발생할 가능성 및 빈도 ($10$: 상시 발생 $\sim 1$: 발생 확률 극미).
  - **검출도 ($D$, Detection)**: 현재 설계/테스트 통제 수단으로 결함을 사전에 탐지하지 '못할' 확률 ($10$: 절대 검출 불가 $\sim 1$: $100\%$ 사전 자동 검출).

</details>

- **상향식 귀납적(Bottom-up Inductive) 전수 조사**: 최하단 컴포넌트 단위에서 출발하여 "이 부품/함수가 오작동하면 상위 시스템에 어떤 피해가 가는가?"를 역으로 파급 추적
- **AIAG-VDA 조치 우선순위(AP: Action Priority) 적용**: 기존 RPN 곱셈 방식의 수학적 왜곡을 극복하기 위해 심각도($S$)를 절대 가중치로 부여하는 2차원 의사결정 매트릭스 채택
- **폐쇄 루프 지속 개선(Closed-loop Re-evaluation)**: 설계 변경(아키텍처 이중화) 및 검출 강화(자동 단위 테스트)를 적용한 후 $S, O, D$ 점수를 재평가하여 잔여 위험(Residual Risk) 승인

#### 한줄 요약
- 상향식 귀납 분석, S/O/D 3대 척도, AIAG-VDA 조치 우선순위(AP), 폐쇄 루프 재평가를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **FMEA 분석 워크시트 5대 핵심 구조 (IEC 60812)**:
  1. **Item / Function**: 분석 대상 모듈 및 정상 동작 사양.
  2. **Failure Mode $\rightarrow$ Effects $\rightarrow$ Causes**: 고장 형태 $\rightarrow$ 상위 파급 영향 $\rightarrow$ 근본 원인 사슬.
  3. **Current Controls**: 현행 예방 통제(Prevention) 및 검출 통제(Detection).
  4. **Initial Scoring**: $S, O, D$ 채점 $\rightarrow RPN = S \times O \times D$ 및 AP 등급 결정.
  5. **Actions & Final Scoring**: 개선 대책 실행 $\rightarrow$ 재평가 $S', O', D' \rightarrow RPN'$ 감소 검증.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. FMEA 고장 인과 사슬 및 위험 평가 구조 (Causal Chain Architecture) ]│
│                                                                         │
│  [ 대상 기능 ] ➔ 데이터베이스 트랜잭션 커넥션 풀 관리 (HikariCP)        │
│       │                                                                 │
│       ▼                                                                 │
│  [ 잠재 고장 모드 ] ➔ DB Connection Leak (커넥션을 반환하지 않고 방치)   │
│       │                                                                 │
│       ├─► [ 상위 영향 (Effects) ] ➔ 신규 결제 요청 전면 거부 (심각도 S = 9) │
│       │                                                                 │
│       ├─► [ 근본 원인 (Causes) ] ➔ 예외 발생 시 finally 블록 누락 (발생도 O = 6)│
│       │                                                                 │
│       └─► [ 현재 통제 (Controls) ] ➔ 수동 단위 테스트만 수행 (검출도 D = 7) │
│                                                                         │
│   초기 위험도: $RPN = 9 \times 6 \times 7 = 378$ (Action Priority: HIGH)│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (개선 조치 및 재평가 파이프라인)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 엔지니어링 개선 조치 및 폐쇄 루프 재평가 (Closed-Loop Re-scoring) ] │
├───────────────────────────────────┬─────────────────────────────────────┤
│ 개선 대책 실행                    │ 재평가 결과 ($S \rightarrow S', O \rightarrow O', D \rightarrow D'$)│
├───────────────────────────────────┼─────────────────────────────────────┤
│ 1. `try-with-resources` 문법 강제 │ 발생도 대폭 감소: $O = 6 \rightarrow O' = 1$ (원인 박멸)│
│ 2. Connection Leak 자동 감지 옵션 │ 검출도 대폭 개선: $D = 7 \rightarrow D' = 2$ (자동 탐지)│
│ 3. 소나큐브(SonarQube) 정적 분석  │ 심각도 유지: $S = 9 \rightarrow S' = 9$ (영향도 불변)  │
│ └─ [ 최종 잔여 위험도 ]           │ $RPN' = 9 \times 1 \times 2 = 18$ (Action Priority: LOW)│
└───────────────────────────────────┴─────────────────────────────────────┘
```

선의 의미: 잠재 고장 모드에서 출발하여 상위 영향(S), 원인(O), 통제(D)를 분석하고 조치 후 RPN을 378에서 18로 대폭 저감하는 구조

| FMEA 구성요소 | 정의 및 핵심 역할 | 평가 기준 | 비고 |
|:---|:---|:---|:---|
| **잠재 고장 모드** | 컴포넌트가 제 기능을 수행하지 못하는 구체적 양상 | 무반응, 지연, 오작동, 간헐적 오류 | Mode |
| **고장 영향 (Effects)** | 상위 모듈, 시스템, 사용자에게 미치는 결과 | 데이터 오염, 시스템 셧다운, 성능 저하 | Severity |
| **고장 원인 (Causes)** | 고장 모드를 직접적으로 촉발한 물리적/코드적 이유 | 메모리 누수, 락 경합, 포인터 예외 | Occurrence |
| **현행 통제 (Controls)**| 현재 적용 중인 예방 설계 및 사전 검출 테스트 | 정적 코드 분석, CI/CD 자동화 테스트 | Detection |
| **조치 우선순위 (AP)** | $S, O, D$의 조합으로 판정되는 개선 조치 강제 등급 | High (필수 조치), Medium, Low | AIAG-VDA |

#### 한줄 요약
- 잠재 고장 모드, 고장 영향(S), 근본 원인(O), 현행 통제(D), 조치 우선순위(AP)로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **FMEA 수행 5단계 수명주기 프로세스**:
  1. 시스템 아키텍처 블록 다이어그램 분석 및 대상 모듈 기능 명세화
  2. 모듈별 잠재 고장 모드, 파급 영향, 근본 원인 브레인스토밍 전수 식별
  3. $S(1\sim10), O(1\sim10), D(1\sim10)$ 채점 및 초기 RPN/AP 산출
  4. AP 등급이 'High'인 항목에 대해 담당자, 개선 완료 기한, 구체적 설계 대책 확정
  5. 설계 개선 적용 후 증거(Test Report)를 검증하고 S'/O'/D' 재평가 및 승인

</details>

```text
1. [시스템 기능 분석 및 범위 확정]
    ├─ 대상 모듈: 클라우드 인증 마이크로서비스 (JWT Token Generator)
    └─ [정상 기능: 유효한 사용자 로그인 시 200ms 내 서명된 JWT 토큰 발급]
            │
            ▼
2. [고장 모드, 영향, 원인 식별]
    ├─ 잠재 고장 모드: JWT 서명 비대칭키 만료 후 자동 갱신 실패
    ├─ 상위 파급 영향: 전사 모든 마이크로서비스 로그인 100% 거부 (치명적)
    ├─ 근본 원인: KMS 키 순환(Key Rotation) 이벤트 리스너 미구현
    └─ [현재 통제: 1년 단위 수동 캘린더 알림 등록 (극도로 취약)]
            │
            ▼
3. [초기 S / O / D 채점 및 AP 등급 산출]
    ├─ 심각도: $S = 10$ (전사 서비스 완전 마비, 인명/보안 위협 수준)
    ├─ 발생도: $O = 5$ (연 1회 정기 발생 가능성)
    ├─ 검출도: $D = 8$ (사전 자동 감지 불가, 장애 발생 후에만 인지)
    ├─ $\text{초기 } RPN = 10 \times 5 \times 8 = 400$
    └─ [AIAG-VDA 판정: Action Priority = HIGH (즉시 설계 변경 필수)]
            │
            ▼
4. [엔지니어링 개선 대책 수립 및 실행]
    ├─ 1. [예방 설계]: AWS KMS 자동 키 순환 API 연동 및 자동 갱신 로직 구현
    ├─ 2. [검출 설계]: 만료 30일 전 자동 검증 헬스체크 프로브 추가
    └─ [3. [비상 대책]: 이전 공개키를 7일간 캐싱하는 Grace Period 설계 반영]
            │
            ▼
5. [개선 효과 검증 및 최종 재평가]
    ├─ 카오스 키 만료 모의 테스트 통과 확인 (증적 확보)
    ├─ 재평가 점수: $S' = 10$ (영향 불변), $O' = 1$ (발생률 0% 수렴), $D' = 1$ (100% 자동 검출)
    ├─ $\text{최종 } RPN' = 10 \times 1 \times 1 = 10$ (Action Priority = LOW)
    └─ [CISO 및 수석 아키텍트 잔여 위험 승인 ➔ 상용 프로덕션 배포]
```

**동작 원리**

1. **상향식 전수 추적(Exhaustive Bottom-up Tracking)**: 모듈의 모든 함수와 인터페이스를 샅샅이 뒤져 단 하나의 예외 케이스(Null Pointer, Timeout)도 누락 없이 수면 위로 노출
2. **AIAG-VDA 조치 우선순위(AP)의 논리성**: $S=10$인 항목은 $O=1, D=1$이더라도 AP 등급을 'High' 또는 'Medium'으로 강제 지정하여 치명적 위험이 곱셈 수치 뒤로 숨는 현상 방어
3. **심각도(S)의 불변성과 $O/D$ 저감 전략**: 고장이 났을 때의 물리적 파괴력(S)은 설계를 완전히 뜯어고치지 않는 한 변하지 않으므로, 예방(O 저감)과 검출(D 저감)을 통해 실질 위험을 제거
4. **증거 기반 평가(Evidence-based Scoring)**: 채점 시 주관적 직관을 배제하고 코드 커버리지 리포트, 단위 테스트 로그, 텔레메트리 실측치를 근거로 $S, O, D$ 점수 부여
5. **지속적 위험 관리 대장(Living Document)**: FMEA 문서를 1회성 서류로 방치하지 않고, 코드 수정 및 신규 기능 추가 시마다 변경점을 반영하는 형상 관리 연계

#### 한줄 요약
- 기능 정의, 고장 모드/인과 식별, S/O/D 채점 및 AP 도출, 엔지니어링 개선 대책 실행, 증거 기반 재평가 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **FMEA 2대 핵심 적용 분야 비교**:
  - DFMEA (Design FMEA): 소프트웨어 아키텍처, 회로, 알고리즘 설계 단계의 결함 분석.
  - PFMEA (Process FMEA): CI/CD 배포, 데이터베이스 마이그레이션, 운영 공정의 결함 분석.

</details>

| 비교 항목 | 설계 FMEA (DFMEA: Design FMEA) | 공정 FMEA (PFMEA: Process FMEA) |
|:---|:---|:---|
| **분석 대상** | **소프트웨어 아키텍처, 데이터 모델, 알고리즘**| **CI/CD 파이프라인, DB 배포 공정, 운영 절차**|
| **핵심 목적** | **설계 결함(Design Flaw) 및 사양 오류 예방** | **작업자 실수(Human Error) 및 배포 사고 예방**|
| **고장 모드 예시** | 메모리 누수, 데드락, 알고리즘 연산 오차 | 잘못된 설정 배포, DB 롤백 실패, 스크립트 오류|
| **개선 조치 방향** | 비동기 넌블로킹 전환, 캐시 도입, 락 튜닝 | 배포 자동화, 블루-그린 무중단 배포, 카나리 롤아웃|
| **수행 시점** | **상세 설계 및 아키텍처 수립 단계** | **운영 환경 구축 및 배포 파이프라인 구성 단계**|
| **국제 표준** | **IEC 60812, AIAG-VDA** | **IEC 60812, AIAG-VDA** |

#### 한줄 요약
- DFMEA는 아키텍처 및 소프트웨어 설계 결함 예방, PFMEA는 CI/CD 및 운영 공정 실수 방지에 특화된다.

## Ⅶ. 결론

- 잠재적 결함이 실제 장애나 사고로 표출되기 전에 설계와 공정의 가장 앞단에서 선제적으로 박멸하는 최고 수준의 예방 신뢰성 공학인 **FMEA 체계**는 단순한 체크리스트를 넘어 시스템의 취약점을 입체적으로 해부하고 치료하는 핵심 예방 백신이며, 실무 구현 시 **IEC 60812 및 AIAG-VDA 표준 기반의 상향식 전수 분석**, **RPN 곱셈 왜곡을 극복하는 조치 우선순위(AP) 매트릭스 적용**, **설계 개선 및 자동화 검출 통제 강화**, **증거 기반의 폐쇄 루프 재평가 거버넌스**를 완성하여 최고 수준의 소프트웨어 무결점 품질과 시스템 신뢰성을 완성

#### 한줄 요약
- 상향식 고장 인과 분석과 AIAG-VDA 조치 우선순위를 통해 잠재 결함을 선제적으로 완벽히 박멸한다.
