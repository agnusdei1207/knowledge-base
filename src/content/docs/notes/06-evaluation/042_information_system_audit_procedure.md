## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **정보시스템 감리**: 독립된 제3자가 정보시스템의 효율성•안전성과 사업관리 적정성을 종합 점검하고 개선을 권고하는 제도이다.
- **독립성**: 감리 주체가 사업 수행•의사결정•이해관계에서 분리되어 객관적으로 판단할 수 있는 상태이다.
- **시정조치 폐루프**: 문제 식별•개선 권고•수정•증거 재검증•잔여위험 확인까지 이어지는 감리 절차이다.

</details>

- 정의/개념: **독립성**을 갖춘 제3자가 사업 관리와 시스템을 점검하는 **정보시스템 감리**이다.
- 배경/필요성: 자체 점검만으로는 위험 발견의 객관성과 **시정조치 폐루프**를 확보할 수 없다.

#### 한줄 요약
- 발주자나 개발사가 아닌 감리법인이 계약•법•기술 기준과 실제 시스템을 맞대어 문제를 찾음이 핵심이다.


## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **감리기준**: 감리 대상•시기•절차•점검항목•보고 방법을 정한 법령•고시상의 준거이다.
- **시정조치 확인**: 사업자가 지적 사항을 수정한 결과와 증거를 감리법인이 다시 검증하는 활동이다.
- **증거 교차 검증**: 문서•인터뷰•로그•실행 결과를 서로 대조해 형식적 준수와 실제 작동을 구분하는 방법이다.

</details>

- 법령•계약•표준을 준거로 하는 **감리기준**이 핵심이다.
- 형식적 준수와 실제 작동을 가르는 **증거 교차 검증**이 핵심이다.
- 잔여 위험과 이행 여부를 확인하는 **시정조치 확인**이 핵심이다.

#### 한줄 요약
- 보고서만 내는 검사가 아니라 발견한 문제가 실제로 고쳐졌는지 증거까지 다시 확인하는 것이 핵심이다.


## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **감리계획서**: 감리 범위•인력•일정•점검 방법과 필요한 자료를 정한 문서이다.
- **감리보고서**: 발견한 문제•영향•근거•개선 권고와 사업자 의견을 기록한 공식 문서이다.
- **감리 증거**: 판정과 개선 권고를 뒷받침하는 문서•인터뷰•로그•시스템 실행 결과이다.
- **잔여 위험**: 시정조치 뒤에도 남아 발주자가 수용•추가 개선 여부를 결정해야 하는 위험이다.

</details>

```text
[발주자]---[감리법인]---[사업자]
              |            |
        [준거•증거]---[시정조치]
```

선의 의미: 발주자와 사업자 사이의 독립 감리법인이 준거•증거 및 시정조치와 연결되는 정보시스템 감리 역할 경계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 발주자 | **감리계획서** 승인과 조치 결과 관리 |
| 감리법인 | **감리 증거**를 바탕으로 독립 점검과 조치 확인 |
| 사업자 | 감리 증거와 수정 결과 제공 |
| 준거•증거 | 법령•계약•표준과 **감리 증거**를 판정 근거로 활용 |
| 시정조치 | **감리보고서**의 지적 원인을 제거하고 **잔여 위험** 보고 |

#### 한줄 요약
- 발주자가 독립 감리를 맡기고 사업자는 증거와 수정 결과를 내며 감리법인이 둘을 검증하는 것이 핵심이다.


## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **예비조사**: 사업 자료와 위험을 분석하여 현장감리의 범위와 중점항목을 정하는 단계이다.
- **현장감리**: 문서•인터뷰•시스템 실행 증거를 대조하여 준거 충족 여부를 확인하는 단계이다.
- **사실 확인**: 감리보고서 확정 전에 발견 사실과 근거를 사업자와 대조해 오류•누락•의견을 반영하는 절차이다.
- **예비조사•감리계획**: 예비조사 결과로 범위•인력•일정•증거 요구를 확정하는 단계이다.
- **감리보고서 작성**: 사실 확인과 사업자 의견을 반영해 문제•근거•개선 권고를 문서화하는 단계이다.

</details>

```text
              [발주자]
                  │ 사업 자료•감리 요청
                  ▼
              [감리법인]
                  │ 1. 예비조사•감리계획
                  │   현장 자료 요청
                  ▼
              [사업자]
                  │ 증거•산출물 제출
                  ▼
              [감리법인]
                  │ 2. 현장감리
                  │ 3. 감리보고서 작성
                  │   보고서 전달
                  ▼
              [발주자]
                  │ 시정조치 요구
                  ▼
              [사업자]
                  │ 조치 결과•증거
                  ▼
              [감리법인]
                  │ 4. 시정조치 확인
                  │
                  ▼
              [발주자]
```

### 동작 원리

1. **예비조사•감리계획**: **예비조사** 결과를 **감리계획서**에 반영한다.
2. **현장감리**: 준거와 산출물•인터뷰•실행 기록을 대조해 문제를 확인한다.
3. **감리보고서 작성**: **사실 확인**과 사업자 의견을 반영해 **감리보고서**를 확정한다.
4. **시정조치 확인**: 수정 결과와 재시험 증거로 이행 여부와 잔여 위험을 판정한다.

#### 한줄 요약
- 위험을 보고 검사 계획을 세운 뒤 현장에서 증거를 확인하고 발견한 문제가 고쳐질 때까지 추적하는 것이 핵심이다.


## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **정보시스템 감리 적용**: 법정 대상이나 고위험 사업을 독립적으로 점검하는 방식이다.
- **프로젝트 관리 조직(Project Management Office, PMO)**: 발주자의 일정•범위•비용•품질•위험 관리를 지원하는 사업관리 조직이다.
- **품질 보증(Quality Assurance, QA)**: 개발 절차와 산출물이 품질 기준을 충족하도록 사업자 내부에서 예방•검증하는 활동이다.

</details>

| 사업 검증 활동 | 정보시스템 감리 | PMO | QA |
|:---|:---|:---|:---|
| 적용 기준 | **정보시스템 감리 적용** | **PMO** | **QA** |
| 핵심 특징 | 제3자의 독립 점검•개선 권고 | 발주자 관점의 사업관리 지원 | 사업자 내부 품질보증 |
| 한계 | 독립성 훼손•형식적 확인 | 의사결정 책임•역할 혼선 | 자기검증에 따른 결함 누락 |

#### 한줄 요약
- 감리는 독립 검사, PMO는 발주자 보좌, QA는 개발팀 자체 품질관리라는 역할 차이가 있다.


## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **형식적 확인**: 문서 제출 여부만 보고 실제 시스템과 통제의 작동 여부를 검증하지 않는 문제이다.
- **표본 대표성**: 선택한 산출물•거래•설정 표본이 전체 위험과 예외를 충분히 나타내는 성질이다.
- **전자적 증거**: 지속적 통합•지속적 제공(Continuous Integration/Continuous Delivery, CI/CD) 로그•형상 이력•시험 결과처럼 생성 시각과 변경 이력을 확인할 수 있는 증거이다.
- **감사 추적성**: 변경 단위의 빌드•시험•승인•배포 기록을 따라 품질 통제의 수행 여부를 확인할 수 있는 성질이다.
- **전자정부법 제57조**: 감리 대상•감리법인 수행•감리기준 준수 근거를 정한 조항이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **형식적 확인**과 **표본 대표성** 부족 | 문서•인터뷰•실행 로그 교차 검증 | 실제 이행 확인 |
| 지적사항의 모호성으로 인한 조치 이행 검증의 한계 | 문제•영향•근거•완료 증거 명시 | 검증 가능성 확보 |
| 짧은 개발 주기로 증거 공백 발생 | **전자적 증거** 수집 | 변경 단위의 **감사 추적성** 확보 |
| 법정 절차 누락 시 감리 결과의 효력이 약화 | **전자정부법 제57조**와 감리기준 준수 | 절차의 법적 정합성 확보 |

#### 한줄 요약
- 짧은 개발 주기마다 자동으로 남은 빌드•시험•승인•배포 로그를 모아 변경별 품질 게이트 통과를 확인한다.


## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **개선 폐루프**: 문제 식별에서 권고•시정•증거 검증•잔여위험 확인까지 완료하는 감리 절차이다.
- **감리 완료 결정**: 시정조치 결과를 독립 증거로 검증하고 미이행•잔여위험을 발주 의사결정에 반영하는 판단이다.

</details>

- 사업 위험별 증거로 **개선 폐루프**를 완성하고 **감리 완료 결정**에 잔여 위험을 반영한다.

#### 한줄 요약
- 문제를 찾는 데서 끝나지 않고 사업자가 고친 결과를 독립된 증거로 확인해야 감리가 끝남이 핵심이다.
