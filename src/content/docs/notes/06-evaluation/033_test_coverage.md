## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **테스트 커버리지(Test Coverage)**: 테스트 스위트가 소스 코드의 제어 흐름 구조를 얼마나 충실히 실행했는지 나타내는 정량 지표.
- **MC/DC(Modified Condition/Decision Coverage)**: 복합 조건식 내 각 개별 조건이 다른 조건과 독립적으로 결과에 영향을 미침을 검증하는 커버리지.

</details>

- 정의/개념: 테스트 케이스 집합이 전체 소스 코드의 구문, 분기, 복합 조건 경로를 얼마나 실행했는지를 측정하는 구조적 품질 지표
- 배경/필요성: 테스트 통과율만으로는 **미실행 사각지대 식별 불가 및 잠재 결함 은폐 위험 방지**

#### 한줄 요약

- 커버리지로 **미실행 경로**를 찾아 시험 보완

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **포섭 관계(Subsumption)**: 상위 커버리지(MC/DC) 충족 시 하위 커버리지(분기, 구문)가 자동으로 만족되는 포함 관계.
- **품질 게이트(Quality Gate)**: CI/CD 파이프라인에서 목표 커버리지 미달 시 배포를 자동 차단하는 검증 장치.

</details>

- 실행 궤적으로 **미시험 요소** 가시화 및 추적
- 구문·분기·MC/DC 순의 **단계적 포섭 관계**
- 위험도 기반 목표 설정과 CI/CD **품질 게이트** 적용

#### 한줄 요약

- 위험도에 따라 **구문·분기·MC/DC** 강도 선택

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **코드 계측(Instrumentation)**: 실행 흐름 추적을 위해 소스 코드에 프로브(Probe)를 삽입하는 기법.
- **테스트 오라클(Test Oracle)**: 테스트 실행 결과의 정답 여부를 판정하는 사전 정의된 기준.

</details>

```text
테스트 커버리지 측정 및 제어 체계 (구조도)
├─ 소스 코드 계측: 컴파일 타임 구문/분기별 프로브 삽입
├─ 테스트 스위트 실행: 단위/통합 테스트 케이스 자동 실행
├─ 실행 흔적 수집: 도달 구문, 분기 참/거짓, MC/DC 쌍 로그 집계
└─ 품질 게이트 판정: 목표 커버리지 달성 검증 / 미도달 코드 보완 지시
```

선의 의미: 소스 코드 계측부터 실행 흔적 수집 및 품질 게이트 판정으로 이어지는 테스트 커버리지 관리 체계.

| 구성요소 | 책임 |
|:---|:---|
| 검증 대상 | 소스·모델의 구조 요소 제공 |
| 시험 집합 | 정상·경계·예외 입력과 기댓값 제공 |
| 계측 도구 | 구문·분기별 **실행 흐름 계측** |
| 실행 흔적 | 미도달 구문·분기의 **실행 흔적** 기록 |
| 품질 게이트 | 목표 비교 후 보완·예외 판정 |

#### 한줄 요약

- 계측 흔적의 **미도달 요소**를 시험으로 보완

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **갭 분석(Gap Analysis)**: 목표 커버리지와 실제 측정치 간의 미실행 코드 블록을 분석하는 과정.

</details>

```text
       품질 관리자
              │ 1. 위험도별 커버리지 목표(구문/분기/MCDC) 설정
              ▼
       계측 도구
              │ 2. 소스 코드 빌드 및 제어 흐름 계측 삽입
              ▼
       테스트 실행 환경
              │ 3. 테스트 스위트 자동 실행 및 실행 궤적 기록
              ▼
       커버리지 분석기
              │ 4. 달성률 측정 및 미도달 경로 갭 분석
              ▼
       개발 및 QA팀
              │ 5. 미도달 경로 테스트 보완 및 데드코드 예외 승인
              ▼
        품질 게이트 통과 및 릴리즈
```

**동작 원리**

1. **목표 수립**: 모듈 위험도에 따라 구문, 분기, MC/DC 목표 백분율 설정
2. **코드 계측**: 제어 흐름 추적 프로브를 주입하여 바이너리 빌드
3. **테스트 실행**: 단위 및 통합 테스트를 수행하며 실행 경로 로그 수집
4. **갭 분석**: 목표치 미달 구간 및 미실행 분기 조건을 가시화
5. **보완 및 승인**: 도달 가능한 경로는 테스트 케이스를 추가하고, 데드코드는 리팩터링 또는 예외 처리

#### 한줄 요약

- 미도달 경로는 시험 보완하고 **도달 불가는 승인**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MC/DC 독립 영향 증명**: 각 개별 조건의 값을 변경했을 때 다른 조건에 상관없이 전체 결정 결과가 반전됨을 보이는 테스트 쌍(Test Pair, N+1개) 구성.

</details>

| 테스트 커버리지 기준 | 구문 커버리지 (Statement) | 분기 커버리지 (Branch) | 수정 조건/결정 커버리지 (MC/DC) |
|:---|:---|:---|:---|
| 적용 기준 | 일반 비즈니스 로직 및 기본 단위 테스트 | 중요 비즈니스 분기 및 의사결정 제어 흐름 | 항공(DO-178C), 자동차(ISO 26262) 안전 필수 로직 |
| 핵심 특징 | 모든 실행 가능 문장을 최소 1회 실행 | 모든 조건문의 참/거짓 분기를 최소 1회 실행 | 각 개별 조건의 독립적 영향력 검증 (N+1개 테스트 쌍) |
| 한계 및 위험 | 실행되지 않은 조건 분기 미검출 | 복합 조건 내부의 마스킹 오류 미검출 | 테스트 케이스 설계 비용 및 시간 증가 |

> 일반 서비스는 구문·분기, 안전 중요 복합 조건은 **MC/DC** 적용

#### 한줄 요약

- 안전 중요 복합 조건은 **MC/DC 독립 영향** 증명

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데드 코드(Dead Code)**: 어떤 실행 흐름으로도 도달할 수 없어 커버리지를 저해하는 미사용 소스 코드.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 높은 달성률의 정답 오류 은폐 | **시험 오라클**로 기댓값 검증 | 기능 결함 누락 보완 |
| 도달 불가 코드의 달성률 저하 | 제거 또는 **예외 근거** 승인 | 지표 왜곡 방지 |
| 안전 모듈의 조건 마스킹 | 위험별 게이트로 **MC/DC** 적용 | 조건별 독립 영향 입증 |

#### 한줄 요약

- 안전 로직은 조건별 **독립 시험 쌍**으로 결과 반전 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 기반 커버리지 관리**: 모든 코드에 100% MC/DC를 적용하는 비효율을 방지하고 위험도에 따라 최적 커버리지 기준을 차등 적용하는 전략.

</details>

- 위험도(SIL/ASIL) 기반 **구문·분기·MC/DC 차등 목표 설정 및 미도달 경로 보완**

#### 한줄 요약

- 미도달은 **시험 보완**, 도달 불가는 근거로 예외 승인
