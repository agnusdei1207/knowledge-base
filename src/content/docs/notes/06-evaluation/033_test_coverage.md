## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **테스트 커버리지(Test Coverage)**: 지정된 테스트 스위트(Test Suite)가 실행될 때 전체 대상 소스 코드의 구문, 분기 조건, 제어 흐름 구조 중 실제로 런타임에 실행을 거쳐 검증이 완료된 요소의 비율을 나타내는 정량적 지표이다.
- **시험 충분성 지표(Test Adequacy Criterion)**: 수행된 테스트가 시스템 내부 구조를 얼마나 촘촘하고 폭넓게 다루었는지를 입증하는 근거 데이터이나, 실행되었다는 사실만 증명할 뿐 결괏값의 정답성이나 기능적 무결성 자체를 보장하지는 않는 한계를 가진 지표이다.
- **미시험 요소(Untested Element)**: 프로젝트에서 설정한 커버리지 목표치 기준 내에 포함되지만 아직 어떠한 테스트 케이스로도 도달(실행)하지 못한 구조 영역으로, 추가 시나리오 보완이나 불가피한 예외 승인 절차가 요구되는 관리 대상이다.
- **수정 조건•결정 커버리지(Modified Condition/Decision Coverage, MC/DC)**: 복합 조건식 내의 각 개별 조건들이 다른 조건의 상태에 관계없이 독립적으로 전체 논리 결정 결과에 영향을 미침을 시험 쌍(Test Pair)으로 수학적으로 증명하도록 요구하는 가장 엄격한 커버리지 기준이다.

</details>

- 정의/개념: 대상 구조 중 실행된 비율인 **테스트 커버리지** 지표
- 배경/필요성: 패스율만으로는 **미시험 요소 식별 불가**

#### 한줄 요약

- 커버리지로 **미실행 경로**를 찾아 시험 보완

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **포섭 관계(Subsumption Relationship)**: 논리적으로 더 엄격한 커버리지 기준(예: 분기 커버리지)을 100% 만족하면, 그보다 약한 하위 기준(예: 구문 커버리지)도 자연스럽게 100% 만족하게 되는 종속적이고 계층적인 포함 관계이다.
- **품질 게이트(Quality Gate)**: 소프트웨어 개발 각 단계(예: 빌드, 배포)에서, 코드 중요도별로 설정된 필수 커버리지 목표치를 미달할 경우 다음 스테이지로의 진입을 시스템적으로 강제 차단하는 품질 통제 정책이다.
- **위험 기반 목표(Risk-based Targeting)**: 사람의 생명과 직결되는 항공, 자율주행, 핵심 금융 원장 모듈일수록 구문 단위를 넘어 MC/DC 같은 가장 강력한 구조 검증 기준과 100%에 근접한 달성 목표를 부여하는 차등화 원칙이다.

</details>

- 실행 궤적으로 **미시험 요소** 가시화·추적
- 구문·분기·MC/DC 순의 **포섭 관계**
- 위험별 목표와 CI/CD **품질 게이트** 적용

#### 한줄 요약

- 위험도에 따라 **구문·분기·MC/DC** 강도 선택

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **구문 커버리지(Statement Coverage)**: 소스 코드 내부의 실행 가능한 명령어 구문들이 테스트 중 최소 한 번 이상 호출되어 실행된 백분율로, 가장 기초적인 커버리지 기준이다(Line Coverage).
- **분기 커버리지(Branch Coverage/Decision Coverage)**: if, switch 등 조건 결정문이 가질 수 있는 최종 참(True)과 거짓(False) 방향의 제어 흐름 경로가 모두 최소 한 번 이상 실행된 비율이다.
- **조건 커버리지(Condition Coverage)**: 전체 결정의 참/거짓 결과와는 무관하게, 조건식 내부를 구성하는 각각의 개별 조건식(예: A>0) 자체가 참과 거짓을 모두 한 번씩 가져본 비율이다.
- **실행 흔적(Execution Trace)**: 코드 내부에 삽입된 센서(Instrumentation)를 통해, 테스트 구동 시 정확히 몇 번째 라인, 어느 분기, 어떤 개별 조건이 참/거짓으로 튕겨 나갔는지 빠짐없이 기록한 런타임 로그 궤적이다.

</details>

```text
              [검증 대상]         [시험 집합]
                       \           /
                        [계측 도구]
                             |
                        [실행 흔적]
                             |
                        [품질 게이트]
```

선의 의미: 계측된 대상의 실행 흔적을 품질 게이트로 판정

| 구성요소 | 책임 |
|:---|:---|
| 검증 대상 | 소스·모델의 구조 요소 제공 |
| 시험 집합 | 정상·경계·예외 입력과 기댓값 제공 |
| 계측 도구 | 구문·분기별 **실행 흐름 계측** |
| 실행 흔적 | 미도달 구문·분기의 **실행 흔적** 기록 |
| 품질 게이트 | 목표 비교 후 보완·예외 판정 |

#### 한줄 요약

- 계측 흔적의 **미도달 요소**를 시험으로 보완

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **계측(Instrumentation)**: 소스 코드 컴파일 시점 혹은 런타임 시 구문 진입점 및 논리 분기점마다 별도의 카운터 코드를 삽입하여, 실제 테스트 실행 시 경로 활성화 여부를 정밀하게 수집하는 기술적 처리 과정이다.
- **도달 불가 코드(Dead Code / Unreachable Code)**: 어떠한 정상 및 비정상 입력값 조합과 제어 흐름의 조합으로도 절대 진입할 수 없는 논리적 모순 코드 블록으로, 커버리지 100% 달성을 가로막으므로 분석 후 삭제 또는 승인(Waiver) 처리가 필요하다.
- **예외 승인(Justification / Waiver Approval)**: 방어적 프로그래밍(예: 발생 확률이 극도로 낮은 하드웨어 결함 대비 코드)이나 도달 불가 코드로 인해 목표 커버리지에 미달한 경우, 개발팀이 작성한 타당성 근거와 파급 영향을 평가위원이 검토해 한시적 수용을 허가하는 행위이다.
- **위험별 커버리지 목표 설정**: 시스템 아키텍처 내 모듈별 장애 파급도(Criticality)를 분류하고, 그에 맞는 커버리지 레벨(구문, 분기, MC/DC)과 필수 달성 비율(예: 80%, 100%)을 차등 할당하는 계획 단계이다.
- **대상 코드•바이너리 계측**: 테스트 대상 코드 또는 실행 파일에 경로 추적을 위한 프로브(Probe)를 삽입하는 빌드 및 환경 구성 단계이다.
- **시험 집합•코드 경로 실행**: 자동화된 테스트 프레임워크를 통해 준비된 시나리오 세트를 구동시켜 대상 코드의 논리 궤적을 활성화하는 수행 단계이다.
- **달성률•미충족 요소 분석**: 생성된 실행 로그와 커버리지 리포트를 분석하여, 목표치 미달 영역과 단 한 번도 실행되지 않은(Red Line) 코드 블록을 식별해내는 단계이다.
- **시험 보완•예외 승인 결정**: 누락된 로직은 테스트 케이스 추가 설계로 메꾸고, 물리적으로 닿을 수 없는 코드는 안전 분석 근거를 첨부해 예외를 확정 짓는 마무리 단계이다.

</details>

```text
시험관리자
   │ 1. 위험별 커버리지 목표 설정
   ▼
커버리지도구
   │ 2. 대상 코드•바이너리 계측
   ▼
시험환경
   │ 3. 시험 집합•코드 경로 실행
   ▼
커버리지도구
   │ 4. 달성률•미충족 요소 분석
   ▼
시험관리자
   │ 5. 시험 보완•예외 승인 결정
```

### 동작 원리

1. **위험별 커버리지 목표 설정**: 모듈별 기준·목표율 선택
2. **대상 코드•바이너리 계측**: 경로 추적용 **계측** 삽입
3. **시험 집합•코드 경로 실행**: 경계·오류 입력으로 경로 실행
4. **달성률•미충족 요소 분석**: 목표 미달과 미도달 요소 식별
5. **시험 보완•예외 승인 결정**: 도달 가능은 보완, 불가능은 승인

#### 한줄 요약

- 미도달 경로는 시험 보완하고 **도달 불가는 승인**

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **결정(Decision)**: "if (A > 0 && B == true)"와 같이 하나 이상의 개별 조건(Condition)들이 AND/OR 논리 연산자로 결합되어, 제어 흐름을 분기시키는 전체 참/거짓 판단의 최종 결과 논리식이다.
- **커버리지 선택(Coverage Selection)**: 업무용 일반 웹 애플리케이션은 구문 및 분기 커버리지 정도로 타협하고, 자율주행이나 항공기 엔진 제어 등 복합 논리 오류 시 대참사가 발생하는 영역은 MC/DC를 의무 적용하는 전략적 분리 기준이다.

</details>

| 테스트 커버리지 기준 | 구문 커버리지 (Statement) | 분기 커버리지 (Branch/Decision) | 수정 조건•결정 커버리지 (MC/DC) |
|:---|:---|:---|:---|
| 시스템 적용 기준 | 일반 업무 로직 | 중요 흐름 제어 | 안전 중요 복합 논리 |
| 핵심 검증 특징 | 모든 **구문** 1회 실행 | **결정**의 참·거짓 실행 | 조건별 독립 영향 증명 |
| 한계 및 기회 비용 | 미실행 분기 은폐 | 조건 마스킹 은폐 | 시험 쌍 설계 비용 증가 |

> 일반 서비스는 구문·분기, 안전 중요 논리는 **MC/DC** 적용

#### 한줄 요약

- 안전 중요 복합 조건은 **MC/DC 독립 영향** 증명

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **높은 커버리지의 한계(Limitations of High Coverage)**: 커버리지 100%라는 숫자는 대상 코드가 한 번씩 활성화되었다는 의미일 뿐, 기획 의도와 다른 잘못된 기댓값 설정, 극한의 경곗값 누락, 동시성 오류 등 런타임의 기능적 결함은 잡아낼 수 없는 태생적 한계이다.
- **예외 근거(Justification/Waiver Evidence)**: 서드파티 라이브러리 내부 코드, 방어적 예외 처리 구문 등 현실적으로 커버하기 불가능한 구조 요소에 대해 커버리지 미달을 허용하기 위해 제출하는 시스템 영향도 평가 및 아키텍트 승인 기록이다.
- **위험별 게이트 운영(Risk-based Gate Operation)**: 단일한 80% 잣대를 모든 코드에 들이대는 대신, 프론트엔드 UI 로직은 구문 70%, 백엔드 결제 코어는 분기 95% 등 아키텍처 리스크에 비례하여 CI 파이프라인의 통과 장벽을 유연하면서도 엄격하게 운영하는 통제 기법이다.
- **시험 오라클(Test Oracle)**: 커버리지의 빈틈인 '정답 검증'을 보완하기 위해, 실제 코드 실행 결과가 요구사항이나 명세서의 기댓값과 정확히 일치하는지 자동화된 메커니즘으로 판정하고 거짓 성공을 걸러내는 잣대이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 높은 달성률의 정답 오류 은폐 | **시험 오라클**로 기댓값 검증 | 기능 결함 누락 보완 |
| 도달 불가 코드의 달성률 저하 | 제거 또는 **예외 근거** 승인 | 지표 왜곡 방지 |
| 안전 모듈의 조건 마스킹 | 위험별 게이트로 **MC/DC** 적용 | 조건별 독립 영향 입증 |

#### 한줄 요약

- 안전 로직은 조건별 **독립 시험 쌍**으로 결과 반전 검증

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **구조 커버리지와 정답성(Structural Coverage & Correctness)**: 화이트박스 관점의 물리적 코드 실행 범위 증거(Coverage)와 블랙박스 관점의 비즈니스 요구사항 결과 정답 증거(Oracle)를 상호 결합하여 융합적으로 퀄리티를 평가하는 포괄적 소프트웨어 품질 확보 철학이다.
- **미충족 요소 처리(Handling Untested Elements)**: 커버리지 측정 후 도출된 미실행 경로(Red Line)에 대해, 입력 조합이 가능한 곳은 집요하게 테스트 코드를 보완하고 물리적 진입이 불가한 곳은 아키텍처 예외 승인 절차를 태우는 체계적 완결 프로세스이다.
- **보완 결정(Supplementation Decision)**: 측정된 수치 이면의 리스크를 꿰뚫어 보고 모듈 중요도에 따라 추가 테스트 강제 작성과 데드 코드의 합법적 예외 승인을 판가름하는 엔지니어링 리더의 의사결정 행위이다.

</details>

- 위험별 커버리지와 오라클을 적용하고 미도달 경로 보완

#### 한줄 요약

- 미도달은 **시험 보완**, 도달 불가는 근거로 예외 승인
