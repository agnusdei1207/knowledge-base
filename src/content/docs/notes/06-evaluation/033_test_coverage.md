## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **테스트 커버리지(Test Coverage)**: 소프트웨어 테스트가 소스 코드의 구조나 요구사항을 얼마나 충실히 실행하고 검증했는지를 나타내는 정량적 척도.
- **구문 커버리지(Statement Coverage)**: 소스 코드 내의 모든 실행 가능한 문장(Statement)이 최소 한 번 이상 실행되었는지를 측정하는 기본 커버리지.
- **결정 커버리지(Decision/Branch Coverage)**: 조건문 전체의 결과가 참(True)과 거짓(False)이 되는 모든 분기(Branch) 경로를 최소 한 번씩 실행했는지를 검증하는 척도.

</details>

- 정의: 대상 구조 중 실행된 비율인 **테스트 커버리지** 지표이다.
- 배경/필요성: 패스율만으로는 **미시험 요소 식별 불가**

#### 한줄 요약

- 커버리지로 **미실행 경로**를 찾아 시험 보완

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **조건 커버리지(Condition Coverage)**: 복합 조건식 내부를 구성하는 개별 조건식(Sub-condition) 각각이 참과 거짓을 최소 한 번씩 만족하도록 테스트하는 척도.
- **조건/결정 커버리지(Condition/Decision Coverage)**: 개별 조건식의 참/거짓과 전체 조건문의 참/거짓 분기를 모두 만족시키는 복합 커버리지.
- **MC/DC(Modified Condition/Decision Coverage)**: 각 개별 조건식이 다른 조건식과 독립적으로 전체 결정문의 결과에 직접 영향을 미침을 증명하는 안전 필수(Safety-Critical) 표준 척도.
- **경로 커버리지(Path Coverage)**: 프로그램 내에서 실행 가능한 모든 독립적 제어 흐름 경로를 검증하는 가장 완벽하지만 조합 폭발이 발생하는 척도.

</details>

- 실행 궤적으로 **미시험 요소** 가시화·추적
- 구문·분기·MC/DC 순의 **포섭 관계**
- 위험별 목표와 CI/CD **품질 게이트** 적용

#### 한줄 요약

- 위험도에 따라 **구문·분기·MC/DC** 강도 선택

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어 흐름 그래프(Control Flow Graph, CFG)**: 프로그램의 실행 경로, 분기점, 루프를 노드와 간선으로 시각화하여 테스트 경로를 도출하는 그래프 모델.
- **테스트 오라클(Test Oracle)**: 테스트 케이스 실행 결과가 참인지 거짓인지를 판단하기 위한 사전 정의된 기대 결과 판정 기준.
- **계측기(Code Instrumentation)**: 코드 실행 경로 및 커버리지 달성 여부를 추적하기 위해 소스 코드에 프로브(Probe)를 삽입하는 도구.

</details>

```text
              [검증 대상]         [시험 집합]
                       \           /
                        [계측 도구]
                             |
                        [실행 흔적]
                             |
                        [품질 게이트]
```

선의 의미: 계측된 대상의 실행 흔적을 품질 게이트로 판정

| 구성요소 | 책임 |
|:---|:---|
| 검증 대상 | 소스·모델의 구조 요소 제공 |
| 시험 집합 | 정상·경계·예외 입력과 기댓값 제공 |
| 계측 도구 | 구문·분기별 **실행 흐름 계측** |
| 실행 흔적 | 미도달 구문·분기의 **실행 흔적** 기록 |
| 품질 게이트 | 목표 비교 후 보완·예외 판정 |

#### 한줄 요약

- 계측 흔적의 **미도달 요소**를 시험으로 보완

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **코드 계측(Instrumentation)**: 컴파일 시점에 실행 추적 코드를 주입하여 실행 로그를 수집 준비하는 단계.
- **테스트 케이스 실행(Test Execution)**: 작성된 테스트 스위트를 실행하여 소스 코드 블록 및 분기를 통과시키는 단계.
- **커버리지 측정 및 미도달 코드 분석(Gap Analysis)**: 미실행 구문과 분기를 식별하고 도달 불가능 코드 제거 또는 테스트 케이스를 보강하는 단계.

</details>

```text
시험관리자
   │ 1. 위험별 커버리지 목표 설정
   ▼
커버리지도구
   │ 2. 대상 코드•바이너리 계측
   ▼
시험환경
   │ 3. 시험 집합•코드 경로 실행
   ▼
커버리지도구
   │ 4. 달성률•미충족 요소 분석
   ▼
시험관리자
   │ 5. 시험 보완•예외 승인 결정
```

### 동작 원리

1. 위험별 커버리지 목표 설정: 모듈별 기준·목표율 선택
2. 대상 코드•바이너리 계측: 경로 추적용 **계측** 삽입
3. 시험 집합•코드 경로 실행: 경계·오류 입력으로 경로 실행
4. 달성률•미충족 요소 분석: 목표 미달과 미도달 요소 식별
5. 시험 보완•예외 승인 결정: 도달 가능은 보완, 불가능은 승인

#### 한줄 요약

- 미도달 경로는 시험 보완하고 **도달 불가는 승인**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **구문 커버리지(Statement Coverage)**: 단순 문장 실행 여부만 확인하여 논리 오류 검출력이 낮으나 측정이 용이한 기본 척도.
- **MC/DC 커버리지(Modified Condition/Decision Coverage)**: 항공(DO-178C), 자동차(ISO 26262 ASIL-D) 등 최고 안전 등급에서 요구되는 고신뢰성 척도.

</details>

| 테스트 커버리지 기준 | 구문 커버리지 (Statement) | 분기 커버리지 (Branch/Decision) | 수정 조건•결정 커버리지 (MC/DC) |
|:---|:---|:---|:---|
| 적용 기준 | 일반 업무 로직 | 중요 흐름 제어 | 안전 중요 복합 논리 |
| 핵심 특징 | 모든 **구문** 1회 실행 | **결정**의 참·거짓 실행 | 조건별 독립 영향 증명 |
| 한계 | 미실행 분기 은폐 | 조건 마스킹 은폐 | 시험 쌍 설계 비용 증가 |

> 일반 서비스는 구문·분기, 안전 중요 논리는 **MC/DC** 적용

#### 한줄 요약

- 안전 중요 복합 조건은 **MC/DC 독립 영향** 증명

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **도달 불가능 코드(Dead/Unreachable Code)**: 커버리지 100% 달성을 저해하는 미사용/예외 코드를 정적 분석으로 식별하고 리팩토링으로 제거.
- **커버리지와 결함 검출률 상관관계**: 높은 커버리지가 결함 부재를 보장하지 않으므로 경계값 분석, 동등 분할 등 블랙박스 기법과 병행 필수.
- **테스트 비용 최적화(Cost-Effectiveness)**: 모든 모듈에 MC/DC를 적용하기 어려우므로 위험도 기반 테스팅(RBT)을 통해 핵심 모듈 중심으로 차등 적용.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 높은 달성률의 정답 오류 은폐 | **시험 오라클**로 기댓값 검증 | 기능 결함 누락 보완 |
| 도달 불가 코드의 달성률 저하 | 제거 또는 **예외 근거** 승인 | 지표 왜곡 방지 |
| 안전 모듈의 조건 마스킹 | 위험별 게이트로 **MC/DC** 적용 | 조건별 독립 영향 입증 |

#### 한줄 요약

- 안전 로직은 조건별 **독립 시험 쌍**으로 결과 반전 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **안전성 등급별 커버리지 기준(Safety Integrity Level-based Coverage)**: 소프트웨어의 위험도와 산업 표준 요구사항에 따라 최적의 커버리지 목표를 수립하고 품질을 보증하는 공학적 접근법.

</details>

- 위험별 커버리지와 오라클을 적용하고 미도달 경로 보완

#### 한줄 요약

- 미도달은 **시험 보완**, 도달 불가는 근거로 예외 승인
