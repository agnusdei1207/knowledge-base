## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **사건수 분석(ETA: Event Tree Analysis / IEC 62502)**: 시스템 내부에 특정한 초기 결함이나 외부 이상 사건(Initiating Event: 예 - 데이터센터 정전, DB 커넥션 풀 고갈)이 발생했을 때, 이에 대응하도록 설계된 일련의 안전 방어 장벽(Safety Barriers: 감지기, 차단기, 자동 페일오버, 비상 발전기)의 성공(Success) 및 실패(Failure) 조합을 시간 순방향(Forward Inductive)으로 이진 분기 전개하여, 최종적으로 도달하는 다양한 사고 결과(안전 종료, 부분 장애, 전면 붕괴)와 시나리오별 발생 확률을 정량적으로 산출하는 위험성 평가 기법.
- **다단계 방어선 붕괴에 따른 대형 참사 전이 결함(Barrier Collapse Defect)**: 초기 장애 자체는 경미했으나 1차 자동 복구 실패 $\rightarrow$ 2차 서킷 브레이커 오작동 $\rightarrow$ 3차 비상 전원 전환 실패로 이어지는 방어 장벽의 연쇄 실패 경로를 사전에 모델링하지 않아 단일 이벤트가 초대형 서비스 붕괴로 확대되는 구조적 결함.

</details>

- 정의/개념: 다계층 방어 심층(Defense in Depth) 구조의 실효성을 수학적으로 검증하기 위해 **초기 사건(Initiating Event) 정의 $\rightarrow$ 시간 순 안전 방어 장벽(Safety Barriers) 배열 $\rightarrow$ 성공($P_i$)/실패($1-P_i$) 이진 분기 트리 전개 $\rightarrow$ 경로별 최종 결과 상태(Consequence) 및 확률 도출 $\rightarrow$ 고위험 취약 경로(Vulnerable Path) 보강** 을 집행하는 **순방향 귀납적 위험 공학 체계**
- 배경/필요성: 초기 고장을 100% 원천 차단하는 것은 불가능하므로, 장애 발생 후 후속 방어 장벽들이 어떻게 작동하여 피해를 국소화(Mitigation)할 것인지 시나리오별 확률과 영향을 사전에 시뮬레이션하기 위해 IEC 62502 표준 ETA 필수화

#### 한줄 요약
- ETA는 초기 사건(Initiating Event)에서 출발하여 방어 장벽의 성공/실패 경로를 순방향으로 전개해 최종 피해 시나리오와 확률을 산출한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ETA 3대 핵심 분석 요소**:
  - **초기 사건 (Initiating Event, $IE$)**: 시스템 정상 상태를 교란하는 최초의 트리거 사건 (연간 발생 빈도 $f(IE)$).
  - **안전 방어 장벽 (Safety Barriers, $B_1, B_2, \dots, B_n$)**: 사고 전파를 저지하기 위해 시간 순으로 작동하는 방어 수단.
  - **결과 상태 (Consequences)**: 모든 장벽을 통과한 최종 종착지 (정상 복원, 성능 저하, 시스템 붕괴).

</details>

- **시간 순방향 귀납적(Forward Inductive) 전개**: 사건이 발생하는 물리적 시간 흐름에 따라 "장애 발생 $\rightarrow$ 1차 감지 $\rightarrow$ 2차 격리 $\rightarrow$ 3차 복구"의 순서로 이진 트리(Binary Tree) 전개
- **조건부 확률(Conditional Probability) 기반 계산**: 각 방어 장벽의 성공/실패 확률은 앞선 장벽의 작동 상태에 영향을 받는 조건부 확률($P(B_k | B_{k-1})$)을 엄격히 반영
- **보타이(Bow-Tie) 모델의 우측 날개**: 좌측 원인 분석(FTA: 결함 나무 분석)과 결합하여, FTA의 Top Event를 ETA의 Initiating Event로 연결하는 전방위 위험 통제 완성

#### 한줄 요약
- 순방향 귀납 전개, 시간 순 방어 장벽 배열, 조건부 확률 계산, 보타이(Bow-Tie) 모델과의 상호보완을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ETA 수목 분기 및 확률 계산 수식 체계 (IEC 62502)**:
  1. 초기 사건 빈도: $f(IE)$ (연간 발생 횟수).
  2. $i$번째 장벽 성공 확률: $P(S_i)$, 실패 확률: $P(F_i) = 1 - P(S_i)$.
  3. 특정 시나리오 경로 확률: $P(\text{Path } k) = f(IE) \times \prod_{i \in Success} P(S_i) \times \prod_{j \in Failure} P(F_j)$.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 사건수 분석 (ETA) 수목 분기 다이어그램 (Event Tree Diagram) ]       │
│                                                                         │
│ [초기 사건]   [방어 장벽 1: 감지]   [방어 장벽 2: 자동전환]  [결과 상태]   [경로 발생 빈도] │
│  (주 전원 정전)   (UPS 감지 및 기동)   (비상 발전기 전환)   (Consequence) (Frequency/yr) │
│                                                                         │
│                  ┌──── 성공 (P1 = 0.99) ─── 정상 복원 (Safe) ➔ f × P1    │
│                  │                                                      │
│    f = 1회/년 ───┤                        ┌─ 성공 (P2 = 0.95) ➔ 10분 지연  │
│                  │                        │  (Degraded) ➔ f × (1-P1) × P2 │
│                  └──── 실패 (1-P1 = 0.01) ─┤                             │
│                                           └─ 실패 (1-P2 = 0.05) ➔ 블랙아웃 │
│                                              (Catastrophic)             │
│                                              ➔ f × (1-P1) × (1-P2)      │
│                                              = 1 × 0.01 × 0.05 = 0.0005 │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 초기 전원 정전 발생 후 UPS 기동 및 비상 발전기 전환의 성공/실패 분기를 거쳐 최종 블랙아웃 확률을 도출하는 구조

| ETA 구성 요소 | 핵심 역할 및 기능 | 수학적 표기 | 설계 의미 |
|:---|:---|:---|:---|
| **초기 사건 (IE)** | 정상 운영을 이탈시키는 고장 사건 정의 | $f(IE) \text{ [events/year]}$ | 위험 평가 출발점 |
| **방어 장벽 (Barrier)**| 장애의 진전을 막는 다계층 방어 수단 | 시간 순서 $B_1 \rightarrow B_2 \rightarrow B_n$| 심층 방어선 |
| **성공 분기 (상향선)**| 해당 방어 장벽이 정상 작동한 경로 | $P(Success) = P_i$ | 위험 억제/완화 |
| **실패 분기 (하향선)**| 해당 방어 장벽이 고장/무력화된 경로 | $P(Failure) = 1 - P_i$ | 위험 심화/확대 |
| **최종 결과 (State)** | 각 경로 도달 시의 시스템 피해 수준 | Safe / Degraded / Catastrophic | 리스크 등급 판정 |

#### 한줄 요약
- 초기 사건(IE), 시간 순 방어 장벽, 상/하향 이진 분기, 최종 결과 상태, 경로 확률 곱으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ETA 수행 및 방어선 최적화 5단계 프로세스**:
  1. 위험도 높은 초기 사건(IE: "주 데이터베이스 Master 노드 패닉") 및 발생 빈도 확정
  2. 이에 대응하는 3대 방어 장벽(B1: 헬스체크 감지 $\rightarrow$ B2: Standby 자동 승격 $\rightarrow$ B3: 읽기 전용 Fallback) 순차 식별
  3. 성공(위)과 실패(아래)로 분기되는 사건수(Event Tree) 도면 작성
  4. 각 분기별 조건부 실패 확률 대입 및 최악의 사고(Catastrophic) 경로 확률 계산
  5. 고위험 취약 경로의 실패 확률을 낮추기 위해 취약 장벽(B2)에 이중화 보강 집행

</details>

```text
1. [초기 사건(IE) 식별 및 발생 빈도 정의]
    ├─ 대상: 글로벌 핀테크 결제 플랫폼
    ├─ 초기 사건(IE): "AWS 가용영역 AZ-1 전체 네트워크 블랙아웃"
    └─ [역대 통계 기반 연간 발생 빈도: $f(IE) = 0.5 \text{회/년}$ (2년에 1회)]
            │
            ▼
2. [시간 순 다계층 안전 방어 장벽(Barriers) 배열]
    ├─ 장벽 1 ($B_1$): Route 53 Anycast DNS 헬스체크 감지 및 트래픽 격리 (성공률 $P_1 = 0.99$)
    ├─ 장벽 2 ($B_2$): AZ-2 Standby 인스턴스 자동 스케일아웃 및 승격 (성공률 $P_2 = 0.90$)
    └─ [장벽 3 ($B_3$): 결제 실패 시 비동기 예약 큐(Dead Letter Queue) 저장 (성공률 $P_3 = 0.95$)]
            │
            ▼
3. [이진 분기 트리 전개 및 시나리오 생성]
    ├─ 경로 1: $B_1(S) \land B_2(S)$ ➔ [정상 서비스 유지, 다운타임 0초]
    ├─ 경로 2: $B_1(S) \land B_2(F) \land B_3(S)$ ➔ [지연 발생하나 결제 예약 성공 (Degraded)]
    └─ [경로 3 (최악): $B_1(F) \land B_3(F)$ ➔ [결제 데이터 영구 소실 및 서비스 다운 (Catastrophic)]]
            │
            ▼
4. [경로별 정량적 발생 확률 및 위험도 산출]
    ├─ 정상 경로 1 발생 빈도: $0.5 \times 0.99 \times 0.90 = 0.4455 \text{ /year}$
    ├─ 최악 경로 3 발생 빈도: $0.5 \times (1-0.99) \times (1-0.95) = 0.00025 \text{ /year}$ (4,000년에 1회)
    └─ [경로 2(장벽 2 실패) 빈도: $0.5 \times 0.99 \times 0.10 = 0.0495 \text{ /year}$ (20년에 1회 발생으로 위험 식별)]
            │
            ▼
5. [취약 방어 장벽 보강 및 아키텍처 확정]
    ├─ 취약한 장벽 2($B_2$: 성공률 90%)를 Multi-AZ 상시 Hot Standby로 개량하여 성공률 $99.9\%$로 승격
    └─ [개선 결과: 성능 저하 장애 발생 빈도가 20년에 1회 ➔ 2,000년에 1회로 위험 100배 감축]
```

**동작 원리**

1. **시간적 인과관계의 엄격성**: 방어 장벽은 반드시 물리적으로 동작하는 시간 순서(감지 $\rightarrow$ 차단 $\rightarrow$ 대체 $\rightarrow$ 완화)대로 나열되어야 논리적 모순이 발생하지 않음
2. **장벽 간 공통 원인 의존성(Barrier Dependency)**: 앞선 장벽 $B_1$이 실패한 이유가 전원 상실 때문이라면, 동일 전원을 쓰는 $B_2$의 성공 확률을 독립적으로 $90\%$라 가정할 수 없으므로 조건부 확률로 모델링
3. **위험의 정량적 서열화**: 각 시나리오의 '발생 빈도 $\times$ 피해 금액'을 곱하여 리스크 매트릭스를 작성하고, 피해가 가장 큰 취약 경로를 1순위로 엔지니어링 보강
4. **보타이(Bow-Tie) 융합 분석**: FTA로 초기 사건(IE)이 발생할 확률을 계산하고, 이를 ETA의 입력으로 주입하여 '원인 발생부터 최종 피해'까지의 엔드투엔드 확률 맵 완성
5. **완화 장벽(Mitigation Barrier)의 중요성**: 장애 차단(Prevention)에 실패하더라도, 마지막 단계의 DLQ(Dead Letter Queue)나 읽기 전용 Fallback이 작동하면 대참사를 방지할 수 있음을 입증

#### 한줄 요약
- 초기 사건 정의, 시간 순 장벽 배열, 이진 분기 전개, 시나리오별 확률 계산, 취약 장벽 보강 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **위험 분석 2대 수목 기법(ETA vs FTA) 비교**:
  - ETA (Event Tree Analysis): 초기 사건에서 출발하는 순방향 귀납 분석 (장벽 성공/실패 시나리오).
  - FTA (Fault Tree Analysis): 최종 고장에서 출발하는 역방향 연역 분석 (원인 논리 게이트 조합).

</details>

| 비교 항목 | 사건수 분석 (ETA: Event Tree Analysis) | 결함 나무 분석 (FTA: Fault Tree Analysis) |
|:---|:---|:---|
| **분석 접근법** | **순방향 귀납적 (Forward Inductive)** | **하향식 역방향 연역적 (Top-down Deductive)**|
| **분석 출발점** | **초기 이상 사건 (Initiating Event)** | **최상위 치명 사고 (Top Event)** |
| **핵심 분석 대상**| **시간 순서에 따른 방어 장벽의 성공/실패** | **컴포넌트 결함들의 AND/OR 논리적 결합** |
| **결과 산출물** | **다양한 최종 사고 시나리오 및 경로 확률** | **시스템 고장 확률 및 최소 컷셋 (MCS)** |
| **주요 적용 목적**| **사고 파급 완화 및 다계층 방어선 검증** | **사고 발생 원인 규명 및 단일 장애점(SPOF) 색출**|
| **국제 표준** | **IEC 62502** | **IEC 61025** |

#### 한줄 요약
- ETA는 순방향 장벽 시나리오 분석(IEC 62502), FTA는 역방향 원인 게이트 분석(IEC 61025)에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ETA 실무 적용 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 방어 장벽들이 상호 독립적이라고 가정하여 **1차 장벽과 2차 장벽이 동일 네트워크 스위치 장애로 동시 실패하는 공통 원인 장애(CCF) 간과** | **앞선 장벽의 실패 원인을 공유하는 후속 장벽에 대해 종속적 조건부 확률($P(B_2 \| B_1=Fail) = 0$)을 명시 적용** | 사고 시나리오 확률 과소평가 100% 방지 |
| 방어 장벽의 배치 순서를 물리적 시간 흐름과 다르게 나열하여 **실제로는 작동하지 않는 허위 복구 경로가 시나리오로 도출되는 오류 발생** | **IEC 62502 표준 지침에 따라 시간적 실행 타임라인(감지 $\rightarrow$ 차단 $\rightarrow$ 페일오버 $\rightarrow$ 완화)을 엄격히 검증 후 트리 전개** | 분석 모델의 공학적 정합성 및 신뢰성 확보 |
| 방어 장벽 수가 10개 이상으로 늘어나 **분기 경로가 $2^{10} = 1024$개로 폭증하여 분석 및 의사결정이 불가능해지는 상태 발생** | **물리적으로 무의미한 분기를 사전에 병합(Pruning)하고, 최종 영향도가 미미한 저위험 경로를 그룹화하여 가지치기 수행** | 고위험 취약 경로 집중 분석 및 효율성 극대화 |

#### 한줄 요약
- 조건부 확률로 CCF를 방어하고, 시간 순 타임라인을 준수하며, 가지치기로 분기 폭증을 최적화한다.

## Ⅶ. 결론

- 초기 결함이 발생했을 때 시스템이 보유한 다계층 방어선이 어떻게 작동하여 피해를 억제하는지를 정량적으로 시뮬레이션하는 **사건수 분석(ETA) 체계**는 단순한 고장 회피를 넘어 장애 전파 차단과 시스템 복원력(Resilience)을 입증하는 핵심 위험성 평가 공학이며, 실무 구현 시 **IEC 62502 표준 준거 시간 순 방어 장벽 모델링**, **조건부 확률 및 공통 원인 고장(CCF)의 정밀 반영**, **FTA와의 보타이(Bow-Tie) 융합 체계 구축**, **최종 고위험 경로에 대한 심층 방어선 보강**을 완성하여 최고 수준의 시스템 내결함성과 무결점 재해 방어 태세를 완성

#### 한줄 요약
- 순방향 장벽 이진 분기와 보타이 모델 융합을 통해 초기 결함의 대형 참사 전이를 완벽히 차단한다.
