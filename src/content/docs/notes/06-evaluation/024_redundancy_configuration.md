## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **이중화 구성(Redundancy Configuration)**: 단일 장애점(SPOF)을 제거하고 서비스 가용성을 보장하기 위해 서버, 네트워크, 스토리지 자원을 다중 배치하는 아키텍처.
- **액티브-액티브(Active-Active)**: 모든 노드가 트래픽을 동시에 처리하며 부하를 분산하고, 한 노드 장애 시 나머지 노드가 부하를 흡수하는 구성.
- **액티브-스탠바이(Active-Standby)**: 주 노드가 서비스를 전담하고 대기 노드는 대기 상태(Hot/Warm/Cold)로 머물다가 주 노드 장애 시 역할을 인계받는 구성.

</details>

- 정의/개념: 필요 용량 $N$에 예비 자원을 더한 **이중화 구조**
- 배경/필요성: 단일 $N$은 장애·정비 이탈 시 **피크 부하 처리 불가**

#### 한줄 요약

- 장애 범위와 예산에 따라 **N+1·2N·2N+1 선택**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **부하 분산(Load Balancing)**: 여러 활성 노드에 요청을 균등 분배하여 리소스 처리량을 극대화하고 응답 지연을 단축하는 기법.
- **대기 자율 전환(Standby Failover)**: 스탠바이 노드가 주 노드의 하트비트 이상을 감지하여 자동으로 마스터 역할을 승계하는 메커니즘.
- **자원 활용률(Resource Utilization)**: Active-Active는 100% 자원을 활용하는 반면 Active-Standby는 평시 대기 자원이 유휴 상태로 유지되는 비용적 차이.
- **정합성 동기화(State Synchronization)**: 노드 간 세션 데이터와 DB 트랜잭션 일관성을 유지하기 위한 실시간 데이터 동기화 기법.

</details>

- 장애 허용 범위가 커질수록 **여유 용량·비용 증가**
- 장애·정비 이탈 후 **잔여 용량 검증** 필수
- 추가 장애를 위한 **정비 여유**와 장애 도메인 분리
- 카오스 부하 시험으로 피크 처리량 실측

#### 한줄 요약

- 수량보다 **잔여 용량·장애 도메인 독립성 검증**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **로드밸런서 계층(Load Balancer Layer)**: L4/L7 스위치 및 GSLB를 통해 클라이언트 트래픽을 활성 인스턴스로 분기하는 진입점.
- **애플리케이션 클러스터(Application Cluster)**: 무상태(Stateless) 또는 분산 세션 기반으로 확장 구성된 복수의 서버 인스턴스.
- **공유/복제 스토리지(Shared/Replicated Storage)**: SAN/NAS 공유 스토리지 또는 분산 스토리지 동기 복제를 통해 데이터 일관성을 제공하는 저장소.

</details>

```text
[최소 픽스 타겟 필수 생존 $N$ 기본 용량 파워 맷집•블랙프라이데이 피크 부하 파도]---[N-1 클론 예비 자원 장비 방패 맷집 쿠션•100% 단절 무적 물리 독립 타 벙커 계통 대군망]
                                               │                                                        │
         [동일 광역 싹쓸이 폭탄 장애 도메인 붕괴 얽힘 커버리지•공통원인 폭탄]-----[L4 DNS 찢기 트래픽 부하분산 렌더링•0.1초 비상 기동 롤백 턴 오토 낚아채 승계 스위치 살림 타결]-----[땜질 수술 픽스 정비•뻗음 지진 폭파 장애•피투성이 무자비 현미경 엑스레이 실측 SLO 검수 점검 크로스체크 락(Lock) 무결 테스트 심판 확인]
```

선의 의미: 용량·예비 자원·장애 도메인·승계·검증 관계

| 구성요소 | 책임 |
|:---|:---|
| 필요 용량 $N$·피크 부하 | **필요 용량**과 처리량 기준 산정 |
| 예비 자원·독립 계통 | 장애 범위에 맞는 **이중화 구성** |
| 장애 도메인·공통 원인 | **장애 도메인 분리**와 동시 실패 억제 |
| 부하분산·자동 승계 | 트래픽 분산과 **자동 전환** |
| 정비·장애·SLO 검증 | 이탈 후 잔여 용량과 목표 실측 |

#### 한줄 요약

- 필요 용량·독립 계통·**이탈 후 잔여 용량 검증**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **트래픽 유입 및 분기(Traffic Ingress & Routing)**: 로드밸런서가 활성 노드의 부하 상태를 확인하고 요청을 최적 노드로 라우팅하는 단계.
- **헬스체크 및 전환 트리거(Health Monitor & Failover Trigger)**: 노드 고장 감지 시 로드밸런서 풀에서 제외하거나 대기 노드를 활성화하는 단계.
- **세션 복제 및 상태 동기(Session Replication & State Sync)**: Redis 클러스터나 DB 복제본을 통해 장애 전후 사용자 세션 및 데이터의 연속성을 유지하는 단계.

</details>

```text
       용량 맷집 쿼터 스루풋 BIA 타겟 최고 책임자 랙
              │ 피크 타겟 용량 파워 맷집 산정 무자비 스캔 도출 도장 락(Lock) 요청 킥
              ▼
       산정기 BIA 엑스레이 심사 타겟 팩트 도출 봇
              │ 1. 1순위 피크 부하 광클 파도 타겟 스파이크 궤적 팩트•최소 필수 생존 $N$ 최저 베이스라인 맷집 용량 파워 치밀 산정 도출 확정 픽스
              ▼
       아키텍처 설계팀
              ├─ 2. 허용 장애•정비 조건 정의
              └─ 3. N+1•2N•2N+1 구성
                          │
                          ▼
       장애 시험기
              │ 4. 장애 주입•자동 승계 실행
              ▼
       SLO 감시기
              │ 5. 잔여 용량•SLO•비용 판정
              ▼
                이중화 수준 확정
```

### 동작 원리

1. 피크 부하•필요 용량 N 산정: 성장률·피크·여유 반영
2. 허용 장애•정비 조건 정의: 동시 고장과 정비 범위 설정
3. N+1•2N•2N+1 구성: 허용 범위에 맞는 구조 선택
4. 장애 주입•자동 승계 실행: 전환과 트래픽 재분배 검증
5. 잔여 용량•SLO•비용 판정: 실측 결과로 수준 확정

#### 한줄 요약

- 장애 주입 후 **잔여 용량·SLO 실측으로 구성 확정**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Active-Active 구성**: 높은 리소스 활용도와 무중단 트래픽 처리를 제공하나 상태 동기화 및 동시성 제어가 복잡한 아키텍처.
- **Active-Standby (Hot/Warm/Cold) 구성**: 구조가 단순하고 데이터 정합성 보장이 용이하나 Failover 지연 시간 및 유휴 자원 비용이 발생하는 아키텍처.

</details>

| 비교 기준 | **N+1** | **2N** | **2N+1** |
|:---|:---|:---|:---|
| 적용 기준 | 단일 자원 장애 | 한 계통 전체 장애 | 계통 장애 중 추가 자원 장애 |
| 구성 | $N$+예비 1대 | 독립 $N$ 계통 2벌 | 독립 $N$ 계통 2벌+예비 1대 |
| 한계 | 복수 장애·피크 여유 부족 | 비용·전환 제어기 SPOF | 복잡성·유휴 비용·공통 원인 |

#### 한줄 요약

- 단일 장애는 N+1, 계통 장애는 2N, 추가 장애는 **2N+1**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **동기화 오버헤드(Replication Overhead)**: Active-Active DB 구성 시 분산 트랜잭션(2PC) 지연을 완화하기 위해 데이터 샤딩 및 결과적 일관성(Eventual Consistency) 적용.
- **용량 사이징(Capacity Sizing N-1)**: N대 중 1대 장애 시에도 남은 N-1대가 전체 피크 부하를 수용할 수 있도록 여유 용량(Headroom) 확보.
- **데이터 충돌 해결(Conflict Resolution)**: 양방향 동시 쓰기 환경에서 타임스탬프(LWW) 또는 CRDT 기반 충돌 해결 규칙 수립.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근거 없는 이중화 수준 | **IEC 61703 RAM** 정량화 | 과잉·과소 투자 방지 |
| 독립 계통의 공유 자원 | 카오스 시험·**실제 독립성 검증** | 공통 원인 고장 억제 |
| 전환 중 전원 공백 | **UPS·독립 전원 경로** | 전환 구간 전력 유지 |
| 이탈 후 잔여 용량 부족 | 피크·정비·장애 혼합 부하 시험 | SLO 달성 여부 실측 |

#### 한줄 요약

- 장애·정비 이탈 후에도 **피크 SLO를 만족하도록 검증**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **업무 특성별 최적 이중화 모델(Workload-optimized Redundancy Architecture)**: 무상태 웹 계층은 Active-Active로, 상태 유지 DB 계층은 Active-Standby(Hot)로 조합하여 성능과 정합성을 균형 있게 달성하는 설계.

</details>

- 단일 장애는 N+1, 계통 장애는 2N, 정비 중 추가 장애는 **2N+1 선택**

#### 한줄 요약

- 장애 주입과 잔여 용량 실측으로 **이중화 수준 확정**
