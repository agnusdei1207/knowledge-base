## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **이중화 구성(Redundancy Configuration)**: 단일 장애점(SPOF) 제거 및 가용성 보장을 위해 자원을 다중 배치하는 아키텍처.
- **필요 용량(N, Base Capacity)**: 피크 부하를 정상 처리하기 위해 요구되는 최소 필수 시스템 자원 용량.

</details>

- 정의/개념: 피크 부하 처리에 필요한 기본 용량 N에 예비 자원을 추가하여 장애 시 연속성을 보장하는 N+1, 2N, 2N+1 이중화 구성 모델
- 배경/필요성: 단일 N 구성 시 노드 장애 또는 정비 이탈 상황에서 **피크 부하 처리 불가 및 전체 서비스 마비 발생**

#### 한줄 요약

- 허용 장애 범위와 예산에 따라 **N+1·2N·2N+1 이중화 수준 차등 설계**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **잔여 용량(N-1 Headroom)**: 노드 장애 또는 정비로 1대가 이탈한 후 남은 시스템이 피크 부하를 감당하는 여유 용량.
- **장애 도메인 분리(Fault Domain Isolation)**: 전원, 네트워크, 랙 단위 격리로 단일 원인에 의한 동시 실패를 억제하는 기법.
- **정비 여유도(Concurrent Maintainability)**: 서비스 중단 없이 계획된 부품 정비나 펌웨어 교체를 수행할 수 있는 능력.

</details>

- 장애 허용 범위 증가에 따른 **여유 용량 및 구축 비용 증가**
- 단일 노드 이탈 후 **피크 부하 수용 잔여 용량 검증**
- 계획 정비 중 추가 장애를 대비한 **장애 도메인 격리**

#### 한줄 요약

- 수량 증설보다 **잔여 용량과 장애 도메인 독립성 검증**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **N+1 이중화(N+1 Redundancy)**: N개의 활성 노드에 예비 노드 1대를 추가하여 단일 부품 장애를 흡수하는 구성.
- **2N 이중화(2N Redundancy)**: 100% 동일한 독립 N 계통을 2벌 구축하여 계통 전체 장애를 방어하는 완전 이중화.
- **2N+1 이중화(2N+1 Redundancy)**: 2N 계통에 예비 노드 1대를 추가하여 정비 중 추가 장애까지 흡수하는 최고 등급 구성.

</details>

```text
이중화 아키텍처 모델 (N+1 / 2N / 2N+1)
├─ N+1 모델: [N 활성 노드 풀] + [1 예비 노드] (단일 노드 장애 대응)
├─ 2N 모델 : [계통 A (N 노드)] ── [계통 B (N 노드)] (완전 독립 2계통)
└─ 2N+1 모델: [계통 A (N 노드)] ── [계통 B (N 노드)] + [1 예비 노드]
```

선의 의미: 기본 필요 용량 N을 기준으로 단일 노드 및 계통 단위 예비 자원을 배치하는 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 기본 필요 용량 N | 피크 부하 기준 최소 필수 처리 용량 확보 |
| N+1 예비 모듈 | 단일 자원 장애 시 즉각 부하 대체 |
| 2N 독립 계통 | 전원·망 완전 분리를 통한 계통 장애 방어 |
| 2N+1 복합 계통 | 계획 정비 중 추가 돌발 장애 흡수 |
| 잔여 용량 검증기 | 장애 이탈 후 SLO 만족 여부 실측 |

#### 한줄 요약

- 필요 용량·독립 계통·**이탈 후 잔여 용량 검증**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **용량 산정(Capacity Sizing)**: 트래픽 피크치와 연간 성장률을 반영해 기본 필요 용량 N을 결정하는 단계.
- **장애 주입 시험(Fault Injection Test)**: 운영 중 임의 노드를 강제 정지시켜 잔여 용량과 Failover를 실측하는 단계.

</details>

```text
       비즈니스 요구분석
              │ 1. 피크 부하 산정 및 필요 용량(N) 도출
              ▼
       아키텍처 설계
              ├─ 2. 허용 장애·정비 조건 정의
              └─ 3. N+1 / 2N / 2N+1 이중화 모델 확정
                          │
                          ▼
       장애 모의시험
              │ 4. 노드 이탈 주입 및 자동 승계 검증
              ▼
       운영 검증팀
              │ 5. 잔여 용량·SLO 충족 여부 실측
              ▼
        최종 이중화 수준 확정
```

**동작 원리**

1. **피크 부하·필요 용량 N 산정**: 비즈니스 성장률과 피크 트래픽을 분석해 최소 필수 용량 N 확정
2. **허용 장애·정비 조건 정의**: 동시 허용 고장 대수 및 무중단 계획 정비 범위 설정
3. **이중화 모델 확정**: 비용과 가용성 목표에 따라 N+1, 2N, 2N+1 아키텍처 선정
4. **장애 주입·자동 승계 실행**: 노드 고장 시뮬레이션을 통해 트래픽 재분배 및 Failover 검증
5. **잔여 용량·SLO 판정**: 1대 이상 이탈 후 남은 인프라의 피크 부하 수용 능력을 실측 평가

#### 한줄 요약

- 장애 주입 후 **잔여 용량·SLO 실측으로 구성 확정**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **티어 등급 연계**: TIA-942 및 Uptime 데이터센터 Tier 등급에 따른 전원·설비 이중화 기준.

</details>

| 구분 | N+1 구성 | 2N 구성 | 2N+1 구성 |
|:---|:---|:---|:---|
| 적용 기준 | 단일 컴포넌트 장애 방어 | 전력/네트워크 계통 전체 장애 방어 | 계획 정비 중 추가 돌발 장애 방어 |
| 핵심 특징 | 활성 N대에 예비 1대 공유 (비용 효율적) | 완전 독립 2개 계통 상시 가동 | 2계통 가동 + 예비 1대 추가 배치 |
| 한계 | 복수 노드 동시 장애 시 처리 용량 부족 | 100% 자원 중복으로 구축 비용 과다 | 극도의 설계 복잡도 및 유휴 비용 소요 |

#### 한줄 요약

- 단일 장애는 N+1, 계통 장애는 2N, 추가 장애는 **2N+1**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IEC 61703**: 가용성 및 신뢰성 평가를 위한 수학적 모델링 국제 표준.
- **공통 원인 고장(Common Cause Failure)**: 단일 전력망이나 스위치 장애로 이중화 계통이 동시 정지하는 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근거 없는 이중화 수준 | **IEC 61703 RAM** 정량화 | 과잉·과소 투자 방지 |
| 독립 계통의 공유 자원 | 카오스 시험·**실제 독립성 검증** | 공통 원인 고장 억제 |
| 전환 중 전원 공백 | **UPS·독립 전원 경로** | 전환 구간 전력 유지 |
| 이탈 후 잔여 용량 부족 | 피크·정비·장애 혼합 부하 시험 | SLO 달성 여부 실측 |

#### 한줄 요약

- 장애·정비 이탈 후에도 **피크 SLO를 만족하도록 검증**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **비용-가용성 최적화(Cost-Availability Optimization)**: 서비스 영향도와 예산 제약을 고려하여 워크로드별 최적 이중화 수준을 선정하는 전략.

</details>

- 서비스 중요도에 따른 **N+1, 2N, 2N+1 이중화 수준 차등 적용 및 잔여 용량 검증**

#### 한줄 요약

- 장애 주입과 잔여 용량 실측으로 **이중화 수준 확정**
