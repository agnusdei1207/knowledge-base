## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **암달의 법칙**: 고정된 작업에서 순차 구간이 병렬 가속비의 상한을 결정한다는 법칙이다.
- **병렬화 비율($P$)**: 전체 기준 실행시간 중 여러 자원으로 나누어 처리할 수 있는 비율이다.
- **가속 상한**: 병렬 자원을 무한히 늘려도 순차 비율 때문에 넘을 수 없는 최대 가속비이다.

</details>

- 정의/개념: 고정 작업의 **순차 비율**로 자원 증가에 따른 가속 상한을 계산하는 법칙이다.
- 배경/필요성: 코어 수만으로는 **순차 구간의 가속 상한 산출할 수 없다**.

#### 한줄 요약
- 아무리 일을 여러 사람이 나누어 처리해도, 혼자서 처리할 수밖에 없는 순서가 정해진 일의 분량이 전체 작업 시간을 결정한다는 법칙입니다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **순차 비율($1-P$)**: 자원 수를 늘려도 병렬화할 수 없어 그대로 남는 실행 비율이다.
- **가속비($S(N)$)**: 단일 자원의 실행시간을 자원 $N$개의 실행시간으로 나눈 값이다.
- **자원 수($N$)**: 병렬 처리에 투입한 코어•프로세서•작업자 수이다.
- **실제 효율 보정**: 이론식에 없는 동기화•통신•부하 불균형 비용을 실측해 자원 증설 효과를 현실적으로 조정하는 과정이다.

</details>

- **가속 축**: $S(N)$으로 자원별 이론 가속비를 계산한다.
- **상한 축**: $1/(1-P)$로 무한 자원의 가속 한계 산출한다.
- **보정 축**: 동기화•통신•불균형으로 실제 효율 보정이다.

#### 한줄 요약
- 컴퓨터 코어를 아무리 많이 늘려도 코드에 남아 있는 순차적인 연산 구간의 장벽 때문에 성능 속도가 무한정 빨라질 수 없습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **병렬 구간**: 입력을 여러 자원에 분할하여 동시에 처리할 수 있는 실행 구간이다.
- **동기화•통신 비용**: 병렬 작업의 상태를 맞추고 데이터를 교환하면서 추가되는 실행시간이다.
- **병렬 효율($S(N)/N$)**: 병렬 자원 하나당 얻은 가속 효과로 자원 증설의 효율을 판단하는 지표이다.

</details>

```text
암달의 법칙 구성
├─ 기준 실행시간
├─ 순차 비율 1-P
├─ 병렬 비율 P
├─ 병렬 자원 수 N
└─ 가속비•효율•상한
```

가지의 의미: 고정 작업의 실행 비율•자원 수와 가속 결과의 정적 산식 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 기준 실행시간 | **단일 자원 실행시간** 측정 |
| 순차 비율 1-P | 자원 수와 무관한 **순차 실행시간** 산출 |
| 병렬 비율 P | 자원 $N$개로 분할할 **병렬 실행시간** 산출 |
| 병렬 자원 수 N | 병렬 구간을 분담할 **처리 자원 수** 설정 |
| 가속비•효율•상한 | **$S(N)$•$S/N$•$1/(1-P)$** 산출 |

#### 한줄 요약
- 일의 성격에 따라 나누어 처리할 수 있는 일과 순차적으로 기다려야 하는 대기 요인이 병렬 자원 수와 결합하여 가속 효과를 결정합니다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **기준 실행시간**: 가속비를 계산할 때 분모•분자의 기준이 되는 단일 자원 실행시간이다.
- **실측 효율**: 이론 가속비 대비 실제 측정한 가속비가 달성한 비율이다.
- **경제성 보정**: 예측 가속비와 실제 성능 향상, 자원 비용을 비교해 튜닝•증설 투자안을 조정하는 절차이다.

</details>

```text
분석가
   │ 고정 작업 분석 요청
   ▼
프로파일러
   │ 1. 기준시간·실행 프로파일 측정
   ▼
구간 분류·계산기
   │ 2. P·N·추가비용 분류
   │ 3. 가속비·효율·상한 산출
   ▼
검증기
   │ 4. 실측 편차·경제성 보정
   ▼
튜닝·증설 투자안
```

**동작 원리**

1. **기준시간•실행 프로파일 측정**: 고정 작업과 환경 기준을 확보한다.
2. **P•N•추가비용 분류**: 순차 비율과 통신 비용을 반영한다.
3. **가속비•효율•상한 산출**: $S(N)$•$S/N$을 산출한다.
4. **실측 편차•경제성 보정**: 예측과 실측의 투자 효과를 비교한다.

#### 한줄 요약
- 소프트웨어 코드를 뜯어보고 병렬 처리가 불가능한 부분을 측정한 다음, 공식에 대입해 최대 성능 한계를 검토합니다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **강한 확장성**: 고정된 작업 크기에서 자원 증가에 따른 실행시간 감소를 평가하는 방식이다.
- **구스타프슨의 법칙**: 자원과 함께 작업 크기를 늘릴 때의 확장 가속비를 설명하는 법칙이다.
- **법칙 선택**: 고정 작업의 실행시간 상한은 암달의 법칙, 자원과 작업 규모의 동시 확장은 구스타프슨의 법칙으로 분석하는 구분이다.

</details>

| 병렬 가속 법칙 | 암달의 법칙 | 구스타프슨 법칙 |
|:---|:---|:---|
| 적용 기준 | 고정 작업의 **실행시간 상한** 분석 | **자원•작업 규모** 동시 확장 |
| 핵심 특징 | **순차 비율**에 따른 가속비 상한 | **확장 작업**의 가속비 추정 |
| 한계 | **병렬 비율** 추정 오류 | **작업 증가 가정** 오류 |

> 요약: 작업 고정은 **암달**, 규모 확장은 **구스타프슨**을 적용한다.

#### 한줄 요약
- 처리할 데이터양이 똑같이 묶여 있을 때와 자원이 늘어나면서 처리할 수 있는 데이터의 규모도 함께 커질 때를 나누어 적용합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **부하 불균형**: 병렬 작업량이 고르게 나뉘지 않아 일부 자원만 오래 실행되는 현상이다.
- **가속 상한**: 자원을 무한히 늘려도 순차 비율 때문에 넘을 수 없는 $1/(1-P)$의 한계이다.
- **과잉 증설**: 통신•동기화 비용으로 병렬 효율이 낮은데도 자원을 추가해 비용만 늘어나는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 규모 변화로 **고정 작업 전제** 위반 | 기준 입력•환경을 고정해 **강한 확장성** 측정 | 자원별 **가속비 비교** 유지 |
| 추정 비율이 코드 실행과 다른 **$P$ 편차** | **프로파일러로 $P$ 실측** | 가속비의 **예측 정확도** 향상 |
| 자원 증가로 커지는 **통신•동기화 비용** | **실측 효율 $S(N)/N$** 비교 | 효과 없는 **과잉 증설** 방지 |

#### 한줄 요약
- 공유 자원 때문에 한 줄로 서는 시간이 많으면 서버를 늘려도 효과가 작습니다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **직렬 구간 튜닝**: 병렬 자원 증설보다 먼저 순차 코드와 동기화 경로의 실행시간을 줄이는 개선이다.
- **투자 판단**: 순차 비율이 크면 직렬 구간을 먼저 튜닝하고 실측 병렬 효율이 높을 때 자원을 증설하는 결정이다.

</details>

- **순차 비율**이 크면 직렬 구간 튜닝, **실측 효율**이 높으면 자원 증설이 핵심이다.

#### 한줄 요약
- 자원 증설 효과를 정량적으로 계산하여 락을 제거하는 소프트웨어 튜닝과 인프라 확장 중 투자 효율성이 높은 결정을 내립니다.
