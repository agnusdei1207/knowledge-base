## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law / Gene Amdahl 1967)**: 고정된 크기의 워크로드(Workload)를 처리할 때, 병렬 처리 프로세서(Core/Node)의 개수를 아무리 무한대($N \to \infty$)로 증설하더라도 전체 시스템의 이론적 최대 가속비(Speedup)는 프로그램 내에 존재하는 순차 실행 구간의 비율($1-p$, Serial Fraction)의 역수($\frac{1}{1-p}$)를 절대 초과할 수 없다는 컴퓨터 아키텍처 수리 법칙.
- **순차 병목에 의한 프로세서 과잉 투자 결함(Diminishing Returns & Amdahl's Wall Defect)**: 소프트웨어 내부의 동기화 락(Lock)이나 단일 스레드 I/O 작업과 같은 순차 실행 구간을 개선하지 않은 채 하드웨어 CPU 코어만 무분별하게 64코어, 128코어로 증설할 경우, 가속비가 급격히 포화되어 수억 원의 인프라 투자 비용 대비 성능 향상이 5% 미만에 그치는 구조적 결함.

</details>

- 정의/개념: 병렬 하드웨어 투자의 비용 효율성과 확장 한계를 정량적으로 도출하기 위해 **프로파일링 기반 순차($1-p$) 및 병렬($p$) 비율 분해 $\rightarrow$ 프로세서 수($N$) 증설에 따른 강한 확장성(Strong Scaling) 가속비 산출 $\rightarrow$ 최대 가속 상한($\lim_{N \to \infty} S(N) = \frac{1}{1-p}$) 도출 $\rightarrow$ 구스타프슨 법칙(약한 확장성) 비교 $\rightarrow$ 직렬 구간 최적화(Lock-free) 및 코어 사이징** 을 집행하는 **병렬 성능 예측 엔지니어링 모델**
- 배경/필요성: 멀티코어 CPU, 대규모 GPU 클러스터, 분산 빅데이터 처리 환경에서 무조건적인 하드웨어 증설을 방지하고 알고리즘 병렬화 투자의 상한선을 사전 검증할 수학적 잣대 필요

#### 한줄 요약
- 암달의 법칙은 고정 작업 크기에서 순차 실행 비율(1-p)이 전체 병렬 가속 상한(1/(1-p))을 결정함을 규명한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙 3대 핵심 수리 변수**:
  - **병렬화 가능 비율 ($p$, Parallel Fraction)**: 전체 프로그램 실행 시간 중 다중 코어로 완벽히 분할 가능한 작업 비율 ($0 \le p \le 1$).
  - **순차 실행 비율 ($1-p$, Serial Fraction)**: 데이터 의존성, 초기화, 락 동기화로 인해 단일 코어에서만 실행되어야 하는 비율.
  - **투입 프로세서 수 ($N$, Number of Processors)**: 병렬 연산에 동시 투입되는 CPU 코어 또는 컴퓨팅 노드 개수.

</details>

- **강한 확장성(Strong Scaling)의 가속 곡선 포화**: 작업 전체 크기를 고정하고 코어 수($N$)를 늘릴 때, 초기에는 선형에 가깝게 가속되나 점차 순차 구간 지연에 수렴(Amdahl's Bottleneck)
- **가속 상한선의 절대성(Asymptotic Speedup Limit)**: $p=0.90$ (90% 병렬화)인 프로그램의 경우 코어를 10,000개 투입해도 최대 가속비는 $\frac{1}{1-0.90} = 10\text{배}$로 물리적 제한
- **직렬 구간 최적화의 높은 ROI**: 병렬 코어를 2배로 늘리는 것보다 순차 구간($1-p$)을 10%에서 5%로 줄이는 것이 전체 시스템 가속비를 2배($10\text{배} \rightarrow 20\text{배}$)로 증대시킴

#### 한줄 요약
- 강한 확장성 포화, 이론적 가속 상한($\frac{1}{1-p}$), 직렬 구간 단축의 최고 ROI를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **암달의 법칙 가속비 공식 유도 과정**:
  1. 단일 프로세서 실행 시간: $T(1) = T_{serial} + T_{parallel} = T_1(1-p) + T_1 p$.
  2. $N$개 프로세서 실행 시간: $T(N) = T_1(1-p) + \frac{T_1 p}{N}$.
  3. 가속비(Speedup) 정의: $S(N) = \frac{T(1)}{T(N)} = \frac{T_1}{T_1(1-p) + \frac{T_1 p}{N}} = \frac{1}{(1-p) + \frac{p}{N}}$.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 단일 프로세서 실행 시간 구조 (Single Core Baseline: T1) ]          │
│                                                                         │
│  ┌───────────────────────────┬────────────────────────────────────────┐ │
│  │ 순차 실행 구간 (1 - p)    │ 병렬 실행 가능 구간 (p)                │ │
│  │ (I/O, 동기화, Lock: 10초) │ (데이터 병렬 연산: 90초)               │ │
│  └───────────────────────────┴────────────────────────────────────────┘ │
│  총 실행시간 T(1) = 10초 + 90초 = 100초 (p = 0.90, 1 - p = 0.10)        │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (N개 코어로 병렬 분할 확장)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. N개 프로세서 병렬 확장 시 실행 시간 구조 (T(N) & Speedup) ]        │
│                                                                         │
│  ┌───────────────────────────┬──────────────┐                           │
│  │ 순차 실행 구간 (1 - p)    │ 병렬 구간/N  │ (N = 10일 때: 90초 / 10 = 9초)
│  │ (단축 불가: 10초 고정)    │ (p / N: 9초) │                           │
│  └───────────────────────────┴──────────────┘                           │
│  총 실행시간 T(10) = 10초 + 9초 = 19초 ➔ 가속비 S(10) = 100 / 19 = 5.26배│
│                                                                         │
│  ┌───────────────────────────┬─┐                                        │
│  │ 순차 실행 구간 (1 - p)    │ │ (N = 100일 때: 90초 / 100 = 0.9초)      │
│  │ (단축 불가: 10초 고정)    │ │                                        │
│  └───────────────────────────┴─┘                                        │
│  총 실행시간 T(100) = 10초 + 0.9초 = 10.9초 ➔ 가속비 S(100) = 9.17배    │
│  무한대 코어(N ➔ ∞) 투입 시 최대 가속비 = 1 / 0.10 = 10.0배 (상한선)    │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 병렬 코어 수($N$)를 늘려도 순차 구간($1-p$)은 줄어들지 않아 전체 실행 시간이 순차 시간에 수렴하는 구조

| 구성 변수 | 수학적 기호 | 의미 및 역할 | 실무 측정 지표 |
|:---|:---|:---|:---|
| **기준 실행 시간** | $T(1)$ | 단일 프로세서 환경의 총 작업 소요 시간 | 1 CPU 코어 실행 프로파일링 시간 |
| **병렬 구간 비율** | $p$ | $N$개 코어에 균등 분할 가능한 연산 비율 | 벡터화(SIMD), 스레드 병렬 루프 시간 |
| **순차 구간 비율** | $1 - p$ | 분할 불가능한 I/O, 뮤텍스 락, 초기화 비율 | Mutex Lock Wait, Disk Sync I/O |
| **가속비 (Speedup)**| $S(N)$ | 단일 코어 대비 $N$개 코어 투입 시 성능 향상 배수 | $\text{Speedup} = \frac{T(1)}{T(N)}$ |
| **병렬 효율 (Efficiency)**| $E(N)$ | 코어 1개당 기여하는 가속 기여도 백분율 | $E(N) = \frac{S(N)}{N} \times 100\%$ |

#### 한줄 요약
- $T(1)$, 병렬 비율($p$), 순차 비율($1-p$), 가속비($S(N)$), 병렬 효율($E(N)$)로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **암달의 법칙 기반 멀티코어 인프라 최적 사이징 5단계 프로세스**:
  1. 단일 코어 환경에서 소프트웨어 실행 프로파일링($T_1$) 수행
  2. 함수별 호출 시간을 분석하여 순차 비율($1-p$)과 병렬 비율($p$) 정밀 분리
  3. 코어 수($N=2, 4, 8, 16, 32, 64$)에 따른 이론 가속비($S(N)$) 및 효율($E(N)$) 계산
  4. 병렬 효율이 70% 이하로 급감하는 최적 코어 수(Inflection Point) 도출
  5. 순차 구간(DB Lock, 동기 I/O)을 비동기/Lock-free로 리팩토링하여 가속 상한 확장

</details>

```text
1. [단일 코어 프로파일링]
    ├─ 배치 이미지 렌더링 프로그램 단일 코어 실행 시간: $T(1) = 60\text{초}$
    └─ [프로파일러(perf/gprof) 측정: 이미지 파일 로딩(I/O) 6초, 픽셀 연산 54초]
            │
            ▼
2. [순차 및 병렬 비율 도출]
    ├─ 순차 구간 비율: $1 - p = \frac{6}{60} = 0.10$ (10%)
    ├─ 병렬 구간 비율: $p = \frac{54}{60} = 0.90$ (90%)
    └─ [이론적 최대 가속 상한: $\lim S(N) = \frac{1}{0.10} = 10\text{배}$]
            │
            ▼
3. [코어 수별 가속비 및 효율 시뮬레이션]
    ├─ $N = 4$코어: $S(4) = \frac{1}{0.10 + 0.90/4} = 3.08\text{배}$ (효율 $77.0\%$)
    ├─ $N = 8$코어: $S(8) = \frac{1}{0.10 + 0.90/8} = 4.71\text{배}$ (효율 $58.8\%$)
    ├─ $N = 16$코어: $S(16) = \frac{1}{0.10 + 0.90/16} = 6.40\text{배}$ (효율 $40.0\%$)
    └─ $N = 64$코어: $S(64) = \frac{1}{0.10 + 0.90/64} = 8.76\text{배}$ (효율 $13.7\%$, 과잉 투자)
            │
            ▼
4. [최적 인프라 코어 사이징 확정]
    ├─ 비용 대비 성능 투자 한계선(효율 50% 이상) 기준으로 $N = 8$코어 서버 선정
    └─ [64코어 고가 서버 도입 계획을 전면 취소하여 인프라 도입 예산 75% 절감]
            │
            ▼
5. [소프트웨어 순차 구간 리팩토링]
    ├─ 파일 로딩을 비동기 메모리 매핑(mmap) 및 멀티스레드 프리페치로 개량
    ├─ 순차 구간 비율 $1-p = 0.10 \rightarrow 0.02$ (2%)로 단축
    └─ [재계산: $N=8$코어에서 가속비 $S(8) = 7.02\text{배}$ (효율 $87.7\%$)로 성능 비약적 상승]
```

**동작 원리**

1. **직렬 구간의 지배력**: 아무리 많은 컴퓨팅 파워를 투입해도 순차적으로 실행되어야 하는 절대 시간($T_1(1-p)$) 미만으로는 작업 시간을 단축 불가
2. **수확 체감(Diminishing Marginal Returns)**: 코어 수가 증가할수록 코어 추가에 따른 가속 증가분($\Delta S$)이 급격히 0에 수렴
3. **병렬 통신 오버헤드 미반영 한계**: 실제 환경에서는 코어 간 캐시 동기화(MESI 프로토콜) 및 버스 대역폭 경합으로 인해 실제 가속비는 암달 이론치보다 더 낮게 나타남
4. **리팩토링 우선 원칙**: 병렬 시스템 튜닝 시 하드웨어 증설 전 소스코드 내 Lock 경합, I/O 대기 구간을 줄이는 것이 유일한 가속 상한 확장 해법
5. **모델 적용 적합성 판단**: 데이터 크기가 고정된 단일 작업의 처리 시간 단축에는 암달의 법칙을 적용하고, 데이터 크기가 함께 커지는 분산 배치에는 구스타프슨 법칙을 적용

#### 한줄 요약
- 단일 코어 프로파일링, p/(1-p) 비율 도출, 코어별 가속비 계산, 최적 코어 사이징, 직렬 구간 리팩토링 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **병렬 컴퓨팅 2대 가속 법칙 비교**:
  - 암달의 법칙 (Amdahl's Law): 고정 작업 크기 (Strong Scaling) $\rightarrow$ 순차 비율에 의한 가속 상한 수렴 ($S(N) = \frac{1}{(1-p) + p/N}$).
  - 구스타프슨의 법칙 (Gustafson's Law): 가변 작업 크기 (Weak Scaling) $\rightarrow$ 코어 수에 비례한 선형 가속 ($S(N) = N - (1-p)(N-1)$).

</details>

| 비교 항목 | 암달의 법칙 (Amdahl's Law) | 구스타프슨의 법칙 (Gustafson's Law) |
|:---|:---|:---|
| **확장성 모델** | **강한 확장성 (Strong Scaling)** | **약한 확장성 (Weak Scaling)** |
| **작업 크기 가정**| **총 작업 크기 고정 (Fixed Workload)** | **프로세서당 작업 크기 고정 (Scaled Workload)**|
| **가속비 공식** | $S(N) = \frac{1}{(1-p) + \frac{p}{N}}$ | $S(N) = N - (1-p)(N-1) = (1-p) + pN$ |
| **무한 코어($N\to\infty$)**| **가속비가 $\frac{1}{1-p}$에 수렴 (상한 존재)**| **가속비가 $N$에 비례하여 무한 증가 (선형 확장)**|
| **핵심 적용 분야**| **단일 이미지 렌더링, 쿼리 응답 시간 단축**| **기상 예측, LLM 분산 학습, 빅데이터 분석** |
| **아키텍처 의미**| 코어 증설의 한계 및 락 튜닝의 중요성 입증 | 대규모 슈퍼컴퓨터 및 GPU 클러스터의 효용성 증명|

#### 한줄 요약
- 암달의 법칙은 고정 작업의 가속 상한을 규명하고, 구스타프슨의 법칙은 대규모 분산 컴퓨팅의 선형 확장을 입증한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **암달의 법칙 실무 적용 시 3대 위험 요소와 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순차 구간 비율($1-p$)을 주관적 추측으로 산정하여 **실제 가속 성능과 수배 이상의 괴리가 발생하고 잘못된 멀티코어 서버 도입** | **Linux `perf`, Java `Async-profiler`를 활용하여 소스코드의 실제 Lock Wait 시간 및 I/O 대기 시간을 나노초 단위로 실측** | 순차 비율 실측 정확도 99% 확보 및 정밀 용량 산정 |
| 암달 공식만 맹신하고 코어를 128개로 증설했으나 **코어 간 캐시 일관성(Cache Coherence) 트래픽 폭증으로 인해 오히려 성능이 역주행 저하** | **암달의 법칙에 코어 간 통신 오버헤드 계수($\alpha$)를 가산한 유니버설 스케일링 법칙(USL)을 병행 적용** | 멀티코어 캐시 버스 경합에 의한 역효과 사전 차단 |
| 데이터베이스 트랜잭션의 Row Lock 경합으로 인해 **스레드 수를 늘릴수록 Lock 대기 시간($1-p$)이 급증하여 가속비가 급격히 하락** | **비관적 락 대신 MVCC 기반 낙관적 락(Optimistic Lock)을 적용하고 자료구조를 Lock-free/CAS(Compare-And-Swap)로 전환** | 순차 구간 비율 90% 감축 및 시스템 가속 상한 대폭 확장 |

#### 한줄 요약
- 프로파일러로 실측하여 오차를 없애고, USL로 캐시 경합을 방어하며, Lock-free로 순차 구간을 제거한다.

## Ⅶ. 결론

- 병렬 컴퓨팅 하드웨어 투자에 대한 냉철한 수학적 한계와 최적의 아키텍처 개선 방향을 제시하는 **암달의 법칙 체계**는 무분별한 하드웨어 증설을 방지하고 소프트웨어 엔지니어링의 본질적 가치를 증명하는 성능 설계의 기본 원리이며, 실무 구현 시 **프로파일러 기반의 객관적 순차 비율($1-p$) 실측**, **코어 수 대비 병렬 효율($E(N)$) 70% 기준의 경제적 사이징**, **소프트웨어 레벨의 Lock-free 및 비동기 I/O 리팩토링**, **대규모 분산 배치 시 구스타프슨 모델과의 상호보완**을 완성하여 최고 수준의 가성비와 병렬 처리 성능을 완성

#### 한줄 요약
- $S(N)=\frac{1}{(1-p)+p/N}$ 수식 분석과 직렬 구간 리팩토링을 통해 최적의 병렬 가속 아키텍처를 완성한다.
