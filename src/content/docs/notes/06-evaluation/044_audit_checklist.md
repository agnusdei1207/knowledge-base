## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **감리 체크리스트(Audit Checklist)**: 감리의 일관성과 객관성을 보장하기 위해 점검 기준과 질문을 체계화한 도구.
- **과업이행 점검**: 제안요청서(RFP) 및 계약서의 요구사항과 개발 산출물 간의 일치 여부를 1:1로 검증하는 체계.

</details>

- 정의/개념: 정보시스템 감리 시 점검의 객관성, 일관성, 완전성을 보장하기 위해 점검 영역별 준거 기준, 질문, 확인 증적, 판정 기준을 표준화한 점검 도구
- 배경/필요성: 감리원 개인 편향에 따른 주관적 판정을 방지하고 **과업 누락 및 결함의 체계적 식별과 시정조치 추적성 확보** #### 한줄 요약

- 준거별 **검증 질문·증거·합격선** 사전 정의

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **준거성(Compliance)**: 전자정부법, 공공 SW 개발보안 가이드, 계약서 등 규정된 표준과의 일치성.
- **실증성(Substantiveness)**: 문서 확인에 그치지 않고 실제 소스 코드, 설정 파일, 실행 로그를 직접 검증하는 성질.

</details>

- 법령·계약·표준에 대한 **준거성** 판정
- 실행 로그·설정·시험 결과의 **실증성** 확보
- 공통 ID의 **추적성** 및 위험 표본 선정

#### 한줄 요약

- 구체 질문과 **실행 증거** 기반 적합성 판정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **항목 식별자(Item ID)**: 점검 준거부터 결함 지적, 시정조치 확인까지 전 과정을 단일 코드로 추적하는 번호.
- **판정 컷오프**: 적합(Pass), 보통(Conditional), 미흡/부적합(Defect)을 가르는 명확한 정량/정성 기준.

</details>

```text
감리 체크리스트 체계 (구조도)
├─ 항목 ID / 준거: 전자정부법 / RFP 과업 요구사항 / SW 개발보안 가이드
├─ 구체 검증 질문: "데이터베이스 암호화 키 관리 절차가 수립되었는가?" 등
├─ 실증 확인 증적: 테이블 DDL / 설정 파일 / 소스 코드 / 테스트 실행 로그
└─ 판정 및 시정조치: 적합·부적합 판정 / 결함 원인 분석 / 조치 완료 조건 명시
```

선의 의미: 공통 항목 ID를 기반으로 점검 준거, 검증 질문, 실증 증적 및 시정조치까지 연계하는 감리 체크리스트 체계.

| 구성요소 | 책임 |
|:---|:---|
| 항목 ID•점검 준거 | **식별자** 및 법령·RFP·표준 연결 |
| 검증 질문 | 준거를 예·아니오 질문으로 변환 |
| 증거•표본 | **감리 증거·고위험 표본** 명시 |
| 판정 기준 | 적합·부적합 **컷오프** 정의 |
| 지적•시정조치 | 원인·영향·패치 증거 연결 |

#### 한줄 요약

- 공통 ID로 **준거·증거·판정·조치** 연결

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **표본 추출(Sampling)**: 전체 산출물 중 결함 발생 가능성이 높고 업무 파급력이 큰 고위험 모듈을 선별하는 기법.

</details>

```text
       감리책임자
              │ 1. 사업 특화 체크리스트 설계 및 점검 질문 확정
              ▼
       위험 기반 추출
              │ 2. 고위험·핵심 기능 중심의 감사 표본(Sample) 추출
              ▼
       현장 실사 점검
              │ 3. 산출물, 소스 코드, 환경 설정, 실행 로그 증적 대조
              ▼
       판정 및 지적
              │ 4. 부적합 판정 및 구체적 결함 원인·조치 권고 작성
              ▼
       시정조치 재확인
              │ 5. 동일 체크리스트 기준으로 사업자 패치 결과 재검증
              ▼
        감리 점검 종결
```

**동작 원리** 1. **체크리스트 설계**: 표준 가이드라인에 프로젝트 특화 요구사항을 결합하여 질문지 생성
2. **표본 선정**: 인터페이스 연계, 대용량 트랜잭션, 개인정보 취급 모듈 우선 추출
3. **증적 대조**: 개발자가 제출한 설계서와 실제 시스템 형상 및 DB DDL을 1:1 교차 검증
4. **결함 판정**: 질문별 합격 컷오프를 적용해 적합 여부를 확정하고 개선 방안 명시
5. **재검증**: 조치 증적을 바탕으로 결함의 완전 제거 여부를 재심사

#### 한줄 요약

- 고위험 표본의 **판정·시정·재검증** 폐루프

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사업관리 vs 기술구조 vs 품질·운영전환**: 프로젝트 거버넌스(관리), 아키텍처/보안(기술), 테스트/배포(품질)의 3대 핵심 점검 분할.

</details>

| 감리 점검 영역 | 사업관리 영역 (Management) | 기술구조 영역 (Architecture) | 품질·운영전환 영역 (QA & Ops) |
|:---|:---|:---|:---|
| 적용 기준 | 계약 준수, 진척율, 범위/일정/비용 통제 | 아키텍처 타당성, DB 모델링, 개발보안 | 단위/통합/성능 테스트, 배포 및 인수인계 |
| 핵심 특징 | WBS 진척, 형상 관리, 변경 승인 이력 점검 | 49개 보안약점, SQL 튜닝, 이중화/DR 검증 | 테스트 커버리지, 성능(TPS), 운영 전환 계획 |
| 한계 | 서류 중심 형식적 일정 점검의 위험 | 복잡한 클라우드/AI 신기술 아키텍처 검증 난이도 | 단기 감리 기간으로 인한 장기 안정성 검증 한계 |

#### 한줄 요약

- 관리·기술·운영 전환의 **책임 영역별 점검** ## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표본 편향(Sampling Bias)**: 사업자가 이미 테스트를 완료한 쉬운 모듈만 감리 표본으로 제출하는 왜곡 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 추상 질문의 판정 편차 | 텍스트 컷오프와 **재현성 통제** | 판정 일관성 확보 |
| 사업자 선정의 **표본 편향** | 관리자·실패 구간 표본 추가 | 치명적 결함 탐지 |
| 문서·실제 불일치 | ID로 설정·로그까지 연결 | 전 생애 추적성 확보 |

#### 한줄 요약

- **고위험 표본·실행 증거** 기반 문서 불일치 식별

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **증적 중심 실질 감리**: 주관적 설문이 아닌 객관적 시스템 로그와 정적 분석 증적을 기반으로 시스템 품질을 보증하는 체계.

</details>

- 공통 ID 기반 **위험 표본 선정, 런타임 실행 증적 교차 검증 및 시정조치 추적** #### 한줄 요약

- **동일 증거·기준의 재현 판정** 및 시정 완료 확인
