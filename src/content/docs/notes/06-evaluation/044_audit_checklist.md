## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **감리 체크리스트(Audit Checklist)**: 정보시스템 감리 시 점검의 일관성, 객관성, 완전성을 보장하기 위해 표준화된 점검 항목과 판단 기준을 정리한 도구.
- **점검 항목(Audit Checkpoints)**: 사업관리, 응용, 데이터베이스, 시스템 아키텍처 및 보안 영역별 필수 점검 사항.
- **과업이행 점검(Contract Compliance Verification)**: 제안요청서와 계약서상의 과업 대비 개발 산출물의 충족 여부를 1:1로 검증하는 체계.

</details>

- 정의/개념: 준거·질문·증거·판정 기준을 엮은 **감리 점검표**
- 배경/필요성: 추상 질문으로는 **판정 재현성 확보 불가**

#### 한줄 요약
- 준거별 **검증 질문·증거·합격선** 사전 정의

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **과업대비표(Task Traceability Matrix)**: 계약상 모든 요구사항이 분석, 설계, 구현, 테스트 산출물로 완전하게 연결되었는지 추적하는 핵심 도구.
- **품질 기준 준수(Quality Standards Compliance)**: ISO/IEC 25010 소프트웨어 품질 모델에 기반하여 기능성, 신뢰성, 사용성, 효율성을 다각도로 검증.
- **보안 및 컴플라이언스(Security & Compliance)**: 소프트웨어 개발보안 가이드 49개 보안 약점 및 개인정보보호법 준수 여부 정밀 점검.
- **객관적 증적(Objective Audit Evidence)**: 단순 주관적 진술을 배제하고 소스 코드, 아키텍처 문서, 테스트 로그 등 물리적 증적에 기반하여 평가.

</details>

- 법령·계약·표준에 대한 **준거성** 판정
- 실행 로그·설정·시험 결과의 **실증성** 확보
- 공통 ID의 **추적성**과 위험 표본 선정

#### 한줄 요약
- 구체 질문과 **실행 증거**로 적합성 판정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사업관리 영역(Project Management)**: 일정 진척, 변경 관리, 형상 관리, 품질 관리 체계 점검.
- **응용시스템 영역(Application System)**: 기능 구현 완성도, 비즈니스 로직 적합성, 인터페이스 연계, 소프트웨어 개발보안.
- **데이터베이스 영역(Database System)**: 데이터 모델링 정규화, 데이터 전환 무결성, 인덱스 및 SQL 튜닝, 백업 정책.
- **인프라 및 시스템 구조 영역(Architecture & Infra)**: 서버/스토리지 사이징 타당성, 네트워크/이중화 구성, 장애 대응 및 모니터링 체계.

</details>

```text
[항목 ID•점검 준거]---[검증 질문]
          |                   |
     [증거•표본]---[판정 기준]---[지적•시정조치]
```

선의 의미: 항목 ID로 준거부터 시정조치까지 연결

| 구성요소 | 책임 및 설계 초점 |
|:---|:---|
| 항목 ID•점검 준거 | **식별자**와 법령·RFP·표준 연결 |
| 검증 질문 | 준거를 예·아니오 질문으로 변환 |
| 증거•표본 | **감리 증거·고위험 표본** 명시 |
| 판정 기준 | 적합·부적합 **컷오프** 정의 |
| 지적•시정조치 | 원인·영향·패치 증거 연결 |

#### 한줄 요약
- 공통 ID로 **준거·증거·판정·조치** 연결

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **체크리스트 맞춤화(Customization & Tailoring)**: 기본 표준 체크리스트에 해당 사업의 특화 과업과 기술 스택을 반영하여 조정하는 단계.
- **문서 및 시스템 실사(Document & System Review)**: 산출물 검토, 소스 코드 정적 분석, 실제 시스템 환경 실사를 수행하는 단계.
- **증적 수집 및 결함 판정(Evidence Collection & Scoring)**: 체크리스트 각 항목별로 적합/보통/미흡/부적합 여부를 증적과 함께 판정하는 단계.
- **조치 권고사항 도출(Recommendation Formulation)**: 식별된 미흡/부적합 항목에 대해 구체적이고 실행 가능한 개선 권고사항을 작성하는 단계.

</details>

```text
              [발주자]
                  │ 점검 범위 전달
                  ▼
              [감리팀]
                  │ 1. 준거•질문 설계
                  │ 2. 위험 표본 선정
                  │   증거 요청
                  ▼
              [사업자]
                  │ 증거•실행 결과
                  ▼
              [감리팀]
                  │ 3. 판정•시정 기준 적용
                  │   시정 요구
                  ▼
              [사업자]
                  │ 조치 증거
                  ▼
              [감리팀]
                  │ 4. 조치 재검증
                  │
                  ▼
              [발주자]
```

### 동작 원리

1. **준거•질문 설계**: 준거를 질문·판정 기준으로 변환
2. **위험 표본 선정**: 모집단에서 고영향·고가능 표본 추출
3. **판정•시정 기준 적용**: 증거 대조와 완료 조건 명시
4. **조치 재검증**: 동일 기준으로 패치·잔여위험 확인

#### 한줄 요약
- 고위험 표본의 **판정·시정·재검증** 폐루프

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **표준 체크리스트(Standard Checklist)**: 전자정부 감리기준에 정의된 범용적이고 일관된 품질 점검 기준.
- **사업 특화 체크리스트(Tailored Checklist)**: 클라우드 전환, AI 도입, 모바일 앱 등 프로젝트 고유 기술 스택에 맞춰 확장된 점검 기준.

</details>

| 감리 점검 영역 분할 | 사업 관리 영역 (Management) | 기술 구조 영역 (Technical) | 품질•운영 전환 영역 (Operation) |
|:---|:---|:---|:---|
| 적용 기준 | 계약·비용·일정 | 아키텍처·코드·보안 | 시험·배포·백업·인수인계 |
| 핵심 특징 | **WBS·변경·승인** | **설계·구현·보안 통제** | **롤백·복구·운영 준비** |
| 한계 | 사업관리 위험 | 기술 구조 위험 | 운영 전환 위험 |

#### 한줄 요약
- 관리·기술·운영 전환의 **책임 영역별 점검**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **체크리스트 형식화 방지(Substantive Audit)**: 단순 체크박스 표기식 점검을 탈피하고 실제 코드와 런타임 환경을 깊이 있게 검증하는 실질 감리 지향.
- **신기술 점검 항목 반영(Modern Tech Stack)**: 컨테이너 오케스트레이션(K8s), 마이크로서비스(API Gateway), 데이터 파이프라인 전용 점검 항목 개발.
- **증적 신뢰성 검증(Evidence Veracity)**: 조작되거나 왜곡된 테스트 결과를 걸러내기 위해 감리원이 직접 테스트 케이스를 재실행하여 검증.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 추상 질문의 판정 편차 | 텍스트 컷오프와 **재현성 통제** | 판정 일관성 확보 |
| 사업자 선정의 **표본 편향** | 관리자·실패 구간 표본 추가 | 치명적 결함 탐지 |
| 문서·실제 불일치 | ID로 설정·로그까지 연결 | 전 생애 추적성 확보 |

#### 한줄 요약
- **고위험 표본·실행 증거**로 문서 불일치 식별

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실효성 중심의 정밀 감리 점검 체계(Evidence-based Practical Audit)**: 체크리스트의 체계적인 맞춤화와 엄정한 증적 기반 평가를 통해 사업의 기술적 결함을 사전 차단하는 핵심 도구.

</details>

- 고위험 준거를 질문·증거·판정으로 만들고 조치까지 추적

#### 한줄 요약
- **동일 증거·기준의 재현 판정**과 시정 완료 확인
