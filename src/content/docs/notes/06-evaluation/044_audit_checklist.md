## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **감리 체크리스트**: 점검 준거·질문·증적·판정 기준을 표준화한 감리 도구.
- **위험 기반 표본 추출**: 영향과 발생 가능성이 큰 대상을 우선 표본으로 고르는 방식.

</details>

- 정의/개념: 점검 질문과 증거·판정 기준을 연결한 **표준 감리 도구**
- 배경/필요성: 정보시스템 감리 현장에서 점검 기준이 모호하고 정성적인 질문에만 의존할 경우, 감리원 개인의 주관적 성향에 따라 점검 품질 편차가 극심해져 피감리인과의 불필요한 소모적 논쟁이 발생하거나, 핵심 위험 영역(개발보안 49개 보안약점, 데이터 모델 정규화, 고가용성 인프라)의 실증 증적을 누락하여 중대 결함이 은폐되는 구조적 한계가 발생함에 따라, 행정안전부/NIA 정보시스템 감리 프레임워크 v3.0에 기반하여 4대 핵심 점검 영역(사업관리, 응용시스템, 데이터베이스, 시스템구조/보안)과 5-Tuple 체크리스트 구조(항목ID, 점검준거, 검증질문, 실증증적, 판정기준)를 수립하는 감리 점검 프레임워크를 도입하여 **감리원 간 점검 객관성 및 판정 일관성 확보, 위험 기반 표본 추출(Risk-based Sampling)을 통한 고위험 결함의 선제적 적발 및 실증 증적 기반의 완벽한 추적성 보증**을 달성할 필요

#### 한줄 요약
- 감리 체크리스트는 질문과 증거·기준을 표준화해 객관적 판정을 돕는다.

## Ⅱ. 특징

- 항목 ID·준거·질문·증적·기준의 **5-Tuple 구조**
- 문서와 실행 시스템을 대조하는 **실증 증적주의**
- 영향이 큰 영역을 우선하는 **위험 기반 표본 추출**
- 요구부터 시정조치까지 연결하는 **항목 ID 추적성**
- 사업 특성을 반영하는 **맞춤형 점검 항목**

#### 한줄 요약
- 5-Tuple, 실증 증거, 위험 표본, ID 추적, 맞춤화가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── 감리 체크리스트 ──────────────┐
│                                            │
├── [점검 영역]                              │
│   ├── 사업관리                             │
│   ├── 응용시스템·개발보안                  │
│   ├── 데이터베이스·데이터                  │
│   └── 시스템구조·보안 인프라              │
│                                            │
└── [항목 레코드]                            │
    └── ID · 준거 · 질문 · 증적 · 판정 기준 │
```

| 구성요소 | 책임 |
|:---|:---|
| **항목 ID** | 지적과 시정조치의 고유 식별 |
| **점검 준거** | 법령·계약·표준의 판단 근거 명시 |
| **검증 질문** | 확인 대상을 폐쇄형 질문으로 구체화 |
| **실증 증적** | 코드·로그·설정 등 판정 자료 지정 |
| **판정 기준** | 적합·부적합의 객관적 경계 정의 |

#### 한줄 요약
- 검증 질문 뒤에 요구 증적과 판정 기준을 같은 레코드로 묶어 두어 감리원 개인의 잣대가 끼어들 자리를 없애고, 항목 ID가 지적과 시정조치를 같은 키로 이어 조치 확인 때 근거를 처음부터 다시 찾는 수고를 없앤다.

## Ⅳ. 흐름도

```text
[사업 산출물·시스템]
     │
     │ 1. 준거·위험 분석
     ▼
[감리팀]
     │ 2. 맞춤형 항목 설계
     │ 3. 위험 기반 표본 선정
     │ 4. 실증 증적 대조와 판정
     │ 5. 동일 항목으로 조치 재검증
     ▼
[발주기관]
     │
     └──────── 판정 결과 반환
```

**동작 원리**

1. **준거·위험 분석**: 법령·계약·아키텍처의 점검 요구 식별
2. **맞춤형 항목 설계**: 질문·증적·합격 기준을 단일 레코드로 정의
3. **위험 기반 표본 선정**: 결제·인증·개인정보 등 고위험 대상 우선 선택
4. **실증 증적 대조와 판정**: 문서와 코드·로그·설정을 교차 확인
5. **동일 항목으로 조치 재검증**: 최초 기준으로 수정 증거를 재판정

#### 한줄 요약
- 위험 기반 표본 선정에서 고위험 대상을 좁혀 볼지 전수를 훑을지가 갈리며, 최초 판정과 재검증을 동일 항목으로 묶어 두지 않으면 시정 여부를 다시 다투는 재실사 비용이 발생한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 감리 체크리스트 | 개발 QA 체크리스트 | 보안 컴플라이언스 체크리스트 |
|:---|:---|:---|:---|
| 점검 주체 | 독립 **감리법인** | 개발 조직의 QA | 보안 관리·심사 조직 |
| 핵심 준거 | 법령·계약·감리 기준 | 기능 명세·개발 표준 | 보안 법규·통제 기준 |
| 주요 증적 | 산출물·코드·DB·설정 | 시험 결과·결함 이력 | 정책·접근·운영 기록 |
| 적용 범위 | 사업 전 영역 | 구현·시험 중심 | 정보보호 관리체계 |
| 핵심 결정 | 사업·과업 적정성 | 릴리스 품질 | 인증·준수 여부 |

#### 한줄 요약
- 감리는 사업 적정성, QA는 개발 품질, 컴플라이언스는 보안 준수를 본다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모호한 질문으로 판정 편차 발생 | 측정 가능한 **정량 합격 기준** 명시 | **판정 일관성** 확보 |
| 사업자가 쉬운 표본만 제시 | 감리원의 **위험 기반 표본** 직접 선정 | **고위험 결함** 적발 |
| 문서와 실제 시스템의 불일치 | 코드·DB·패킷의 **교차 실사** | **실증 신뢰도** 확보 |
| 표준 항목의 기계적 적용 | 사업 기술·규제에 맞춘 **항목 조정** | **점검 적합성** 향상 |
| 조치 단계에서 지적 이력 단절 | 항목 ID 기반 **폐쇄 루프 추적** | **시정 완결성** 보증 |

#### 한줄 요약
- 정량 기준, 위험 표본, 교차 실사, 항목 조정, ID 추적을 적용한다.

## Ⅶ. 결론

- 공공 및 엔터프라이즈 정보시스템의 4대 핵심 기술 영역을 정량적이고 객관적인 기준으로 전수 검증하여 감리 품질의 일관성과 실효성을 보증하는 **정보시스템 감리 점검 기준 및 프레임워크(Information System Audit Checklist / Framework v3.0 & 5-Tuple Structure / Risk-based Sampling)의 핵심 기술 표준**으로 확고히 자리 잡았으며, 데브섹옵스(DevSecOps) 및 자동화된 보안/정적 분석 도구와 연계된 디지털 감리 체계로 발전하는 가운데, 실무 체크리스트 작성 및 현장 점검 시에는 **모호성을 배제한 폐쇄형 검증 질문과 정량적 합격 기준 명문화, 피감리인이 제출하는 산출물 문서를 넘어 실제 구동 소스코드·DB 스키마·네트워크 패킷을 교차 실사하는 실증 증적주의 관철, 최초 지적된 항목 ID를 시정조치 확인까지 1:1로 결속하는 폐쇄 루프 추적성 유지**를 결합하여 완벽한 감리 신뢰성을 완성

#### 한줄 요약
- 위험 기반 표본을 실증 증거로 판단하고 같은 기준으로 조치를 확인한다.
