## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SLI**: 서비스 수준을 관측하는 지연·처리량·오류율 등의 지표.
- **SLO**: SLI가 달성해야 할 정량 목표.
- **꼬리 지연**: 일부 느린 요청에서 나타나는 높은 백분위수 지연.

</details>

- 정의/개념: 전 구간 병목을 측정·개선·재검증하는 **성능 관리 폐루프**
- 배경/필요성: 평균 응답시간만으로는 일부 요청의 **p99 꼬리 지연 식별 불가**

#### 한줄 요약
- 성능 관리는 SLO를 기준으로 전 구간 병목을 찾아 개선하고 재검증한다.

## Ⅱ. 특징

- 사용자 체감과 사업 목표를 잇는 **SLI·SLO**
- 평균의 왜곡을 줄이는 **p95·p99 백분위수**
- 처리율·오류·지연을 보는 **RED 방법론**
- 사용률·포화·오류를 보는 **USE 방법론**
- Trace ID와 Span 기반 **분산 추적**
- 동일 부하로 병목 전이를 찾는 **회귀 성능 시험**

#### 한줄 요약
- SLO, 백분위수, RED·USE, 분산 추적, 회귀 시험이 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── 성능 관리 체계 ──────────────┐
│                                           │
├── [사용자·클라이언트]                     │
│   └── 렌더링 · DNS · TLS                  │
├── [애플리케이션]                          │
│   └── 스레드 · GC · 동기 I/O              │
├── [데이터베이스]                          │
│   └── 실행계획 · 인덱스 · 락 · 버퍼       │
└── [인프라·네트워크]                       │
    └── CPU · 메모리 · I/O · RTT            │
```

| 구성요소 | 책임 |
|:---|:---|
| **사용자·클라이언트** | 단말과 전송 초기 지연 측정 |
| **애플리케이션** | 실행·스레드·메모리 병목 진단 |
| **데이터베이스** | 쿼리·락·저장소 병목 진단 |
| **인프라·네트워크** | 자원 포화와 전송 지연 진단 |
| **관측·추적 계층** | Metrics·Logs·Traces 상관 분석 |

#### 한줄 요약
- 사용자, 애플리케이션, DB, 인프라와 관측 계층으로 구성된다.

## Ⅳ. 흐름도

```text
[서비스 요구]
     │
     │ 1. SLI·SLO 정의
     ▼
[성능 관리팀]
     │ 2. 기준선·부하 계측
     │ 3. 임계 경로·병목 분석
     │ 4. 병목 원인별 최적화
     │ 5. 동일 부하 회귀 검증
     ▼
[배포 책임자]
     │
     └──────── 승인 결과 반환
```

**동작 원리**

1. **SLI·SLO 정의**: 워크로드별 지연·처리량·오류 목표 설정
2. **기준선·부하 계측**: 재현 가능한 부하와 텔레메트리 수집
3. **임계 경로·병목 분석**: RED 증상과 USE 자원 원인의 상관 분석
4. **병목 원인별 최적화**: 코드·쿼리·자원 중 원인 지점 개선
5. **동일 부하 회귀 검증**: 목표 달성과 병목 이동·부작용 확인

#### 한줄 요약
- 목표, 계측, 분석, 최적화, 동일 부하 검증의 폐루프로 수행한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | RED | USE | APM 분산 추적 |
|:---|:---|:---|:---|
| 관점 | 서비스 요청 | 시스템 자원 | 코드·호출 경로 |
| 핵심 지표 | Rate·Errors·Duration | Utilization·Saturation·Errors | Trace·Span·호출 지연 |
| 핵심 질문 | 사용자 증상이 있는가 | 자원이 포화됐는가 | 어느 호출이 지연됐는가 |
| 주요 역할 | **증상 탐지** | **자원 원인 진단** | **임계 경로 식별** |
| 적용 위치 | API·서비스 진입점 | CPU·메모리·디스크·망 | 서비스·메서드·SQL |

#### 한줄 요약
- RED는 증상, USE는 자원 원인, APM은 호출 경로를 진단한다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| 평균값에 가려진 느린 요청 | p95·p99 기반 **꼬리 지연 관리** |
| 상위 계층 증설로 하위 병목 전이 | 전체 경로의 **용량 균형 검증** |
| APM 전수 수집의 관측 오버헤드 | 오류·지연 중심 **적응형 샘플링** |
| 운영과 다른 부하 시험 결과 | 실제 분포의 **워크로드 모델** 적용 |
| 튜닝 후 기능·안정성 저하 | 성능·기능 **통합 회귀 게이트** |

#### 한줄 요약
- 꼬리 지연, 용량 균형, 샘플링, 실제 부하, 회귀 게이트를 통제한다.

## Ⅶ. 결론

- p99 SLO 미달 시 **임계 경로 병목**을 개선하고 동일 부하로 배포 결정

#### 한줄 요약
- 체감 SLO를 기준으로 가장 큰 병목을 개선하고 전 경로를 재검증한다.
