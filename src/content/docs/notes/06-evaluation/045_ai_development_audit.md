## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AI 개발 사업 특수 감리(AI Development Audit / ISO/IEC 42001 & NIST AI RMF)**: 전통적인 절차적 소스코드 감사 방식으로는 검증할 수 없는 인공지능(머신러닝/딥러닝/LLM) 시스템의 고유한 확률적 특성(Stochastic Nature), 블랙박스 불투명성, 데이터 편향(Bias), 성능 드리프트(Drift), 생성형 AI의 환각(Hallucination) 및 프롬프트 주입 위험을 통제하기 위해, 학습 데이터 수집$\cdot$정제부터 모델 학습, 평가, MLOps 배포 및 런타임 운영에 이르는 AI 전 생애주기에서 품질, 공정성, 설명가능성, 안전성을 독립 제3자가 종합 점검하는 특수 감리 체계.
- **블랙박스 확률 오류 및 런타임 모델 붕괴 결함(AI Blackbox & Model Drift Defect)**: 개발 시점의 정적 테스트 데이터셋에서는 정확도 95%를 기록했으나, 실제 상용 배포 후 입력 데이터 분포의 변화(Data Drift)로 인해 오작동이 폭증하거나, 특정 성별/인종에 대한 편향 판정으로 법적 소송을 당하고 프롬프트 인젝션 공격에 사내 기밀이 유출되는 구조적 결함.

</details>

- 정의/개념: 인공지능 시스템의 안전성과 윤리적 신뢰성을 기술적으로 보증하기 위해 **데이터 수집 적법성 및 계보(Lineage) 검증 $\rightarrow$ 불변 식별자(Immutable Hash) 기반 모델 재현성(Reproducibility) 시험 $\rightarrow$ 공정성(Fairness) 및 적대적 공격(Adversarial Robustness) 실사 $\rightarrow$ 설명가능성(XAI) 및 프롬프트 가드레일 확인 $\rightarrow$ MLOps 드리프트 감시 및 인간 감독(HITL: Human-in-the-Loop) 체계 확립** 을 집행하는 **AI 전 생애주기 품질 감리 체계**
- 배경/필요성: EU AI Act(인공지능법) 및 과학기술정보통신부 인공지능 윤리기준 제정, 공공 AI 도입 의무화에 따라 고위험 AI 시스템에 대한 객관적 신뢰성 감리 및 알고리즘 투명성 확보 필수화

#### 한줄 요약
- AI 개발 감리는 데이터 계보, 모델 재현성, 공정성, MLOps 드리프트 감시, 인간 감독(HITL)을 전 생애주기에서 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **AI 감리 4대 핵심 검증 기제**:
  - **데이터 계보 (Data Lineage)**: 원천 데이터 수집 출처, 저작권, 라벨링 검수, 전처리 파이프라인의 전 과정 추적성 보증.
  - **모델 재현성 (Model Reproducibility)**: 소스코드(Git), 데이터셋(DVC), 모델 가중치(MLflow)를 단일 불변 해시로 결속하여 언제든 동일 성능 재현.
  - **알고리즘 공정성 (Algorithmic Fairness)**: 집단 간 이질적 영향(Disparate Impact) 및 균등 기회(Equalized Odds) 지표 검증.
  - **인간 감독권 (Human-in-the-Loop, HITL)**: 고위험 AI 판정 시 인간 전문가가 최종 승인하거나 비상 차단(Circuit Breaker)할 수 있는 제어권 확보.

</details>

- **전통적 코드 중심 감리에서 데이터-모델 중심 감리로 전환**: 코드가 아닌 '데이터'가 로직을 결정하는 패러다임에 맞춰 데이터 품질 지표(완전성, 유효성, 편향도)를 최우선 실사
- **생성형 AI (LLM / RAG) 특화 안전성 검증**: 환각(Hallucination) 방지를 위한 RAG 그라운딩(Grounding) 검증, 프롬프트 인젝션(Prompt Injection) 방어 필터, 탈옥(Jailbreak) 모의 침투 수행
- **MLOps 기반 지속적 드리프트 모니터링 체계**: 모델 배포 후 데이터 드리프트(Data Drift) 및 개념 드리프트(Concept Drift) 발생 시 자동 경보 및 롤백 파이프라인 실사

#### 한줄 요약
- 데이터 계보 추적, 불변 해시 모델 재현성, XAI 설명가능성, LLM 프롬프트 가드레일, HITL 인간 감독권을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AI 감리 프레임워크 4대 생애주기 점검 계층 (ISO/IEC 42001)**:
  1. **데이터 구축 및 전처리 계층**: 수집 적법성, 라벨링 합의도(Kappa), 클래스 불균형, 개인정보 비식별화.
  2. **모델 학습 및 평가 계층**: 정량 메트릭(F1, AUC, BLEU), 하이퍼파라미터 추적, 공정성/편향성, 적대적 강건성.
  3. **설명가능성 및 보안 계층**: SHAP/LIME 특성 기여도, 모델 역공학 방어, 프롬프트 인젝션 차단기.
  4. **MLOps 서빙 및 운영 계층**: 실시간 드리프트 탐지(PSI/KS-test), 자동 재학습, 롤백, 인간 최종 승인권.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. ISO/IEC 42001 준거 AI 생애주기 4대 감리 점검 아키텍처 ]            │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 1. 데이터 구축 감리 (Data) ]    │ [ 2. 모델 학습/평가 감리 (Model) ]  │
│ ├─ 저작권/개인정보 적법성 검증    │ ├─ 정량 성능(F1/AUC) 공인 BMT 실사  │
│ ├─ 라벨링 검수 합의도(Kappa > 0.8)│ ├─ 불변 해시(Git+DVC) 100% 재현성   │
│ └─ DVC 기반 데이터 계보(Lineage)  │ └─ 공정성 지표(Disparate Impact) 검증│
├───────────────────────────────────┼─────────────────────────────────────┤
│ [ 3. XAI 및 보안 가드레일 감리 ]  │ [ 4. MLOps 운영/서빙 감리 (Ops) ]   │
│ ├─ SHAP/LIME 기반 판정 근거 제시  │ ├─ PSI 기반 Data Drift 실시간 알림  │
│ ├─ 프롬프트 인젝션/탈옥 방어 필터 │ ├─ 성능 저하 시 즉각 롤백 파이프라인│
│ └─ RAG 그라운딩(문맥 충실도) 실측 │ └─ [인간 감독권(HITL) 비상 차단기] │
└───────────────────────────────────┴─────────────────────────────────────┘
```

선의 의미: 데이터 수집부터 모델 학습, 설명가능성, MLOps 운영 서빙에 이르기까지 AI 전 주기를 4개 영역으로 구조화한 감리 프레임워크

| AI 감리 영역 | 핵심 점검 항목 | 실증 확인 증적 | 주요 기술 및 지표 |
|:---|:---|:---|:---|
| **데이터 구축** | 출처 적법성, 라벨링 품질, 편향도 | 데이터 계보도, 라벨링 검수 리포트 | Cohen's Kappa, Shannon Entropy |
| **모델 평가** | 알고리즘 성능 및 학습 재현성 | MLflow 파이프라인 로그, 학습 스크립트| F1-score, 불변 식별자(SHA-256) |
| **공정성/윤리** | 인구통계학적 집단 간 편향 차별 | 공정성 평가 매트릭스 리포트 | Disparate Impact Ratio ($0.8 \sim 1.25$)|
| **보안/설명성** | XAI 근거 제시 및 프롬프트 방어 | SHAP 시각화 결과서, 침투 테스트 로그| SHAP, LIME, NeMo Guardrails |
| **MLOps 운영** | 데이터 드리프트 및 롤백 절차 | Prometheus/Evidently 대시보드 | PSI (Population Stability Index) |

#### 한줄 요약
- 데이터 구축(계보), 모델 학습(재현성), XAI/보안(가드레일), MLOps 서빙(드리프트/HITL)의 4대 계층으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **AI 개발 사업 감리 실사 5단계 프로세스**:
  1. AI 서비스의 비즈니스 영향도(신용평가, 채용, 의료 등 고위험군) 분석 및 허용 오차 기준 확정
  2. 원천 데이터 수집 출처 계약서, 개인정보 비식별 조치, DVC 데이터셋 계보 실사
  3. 감리원이 독립 환경에서 Git 커밋과 MLflow 아티팩트를 로드하여 모델 학습 100% 재현
  4. 공정성 지표 및 적대적 노이즈 주입(FGSM 공격)을 인가하여 모델 강건성 실측
  5. MLOps 파이프라인의 드리프트 알림 임계치와 인간 감독 비상 차단기 동작 확인 후 승인

</details>

```text
1. [AI 위험 등급 분류 및 감리 기준 수립]
    ├─ 대상: AI 기반 금융 대출 심사 및 신용평가 자동화 시스템
    ├─ EU AI Act / 국가 기준 판정: '고위험(High-Risk) AI 시스템' 분류
    └─ [감리 기준: 성능(F1 > 0.90) + 공정성(차별 금지) + 설명가능성(XAI) 의무화]
            │
            ▼
2. [데이터 구축 및 계보(Lineage) 실사]
    ├─ 1,000만 건 대출 데이터셋 출처 적법성 검토 ➔ 개인정보 가명처리 적정성 확인
    ├─ 라벨링 검수: 불일치율 0.5% 이하(Kappa 0.92) 확인 (Pass)
    └─ [DVC 추적: 원천 데이터 ➔ 정제 ➔ 피처 엔지니어링 전 과정 계보 증적 확인]
            │
            ▼
3. [불변 해시 기반 모델 학습 재현성(Reproducibility) 시험]
    ├─ 감리원이 테스트베드에서 `git checkout v1.0` 및 `dvc pull` 실행
    ├─ 고정된 시드(Seed=42)로 모델 재학습 수행 ➔ F1-score 0.925 오차 없이 100% 재현
    └─ [판정: 모델 재현성(Reproducibility) 완전 입증]
            │
            ▼
4. [공정성(Fairness) 및 XAI 설명가능성 검증]
    ├─ 성별/연령별 승인율 검증: Disparate Impact Ratio = 0.91 ($0.8 \sim 1.25$ 충족, Pass)
    ├─ 대출 거절 고객에 대해 SHAP 알고리즘으로 상위 거절 사유(연체 이력 등) 자동 출력 검증
    └─ [적대적 공격 시험: FGSM 노이즈 주입 시에도 예측 정확도 88% 유지 확인 (강건성 입증)]
            │
            ▼
5. [MLOps 운영 통제 및 HITL 인간 감독권 확인]
    ├─ 거시경제 지표 변동 시 PSI(Population Stability Index) > 0.25 발생 감지 알림 테스트
    ├─ 드리프트 발생 시 즉각 과거 안정 버전으로 원클릭 롤백 파이프라인 동작 확인
    └─ [최종 판정: "적합(Pass)" 감리보고서 발간 ➔ 신뢰할 수 있는 공공 AI 서비스 배포]
```

**동작 원리**

1. **불변 식별자(Immutable Identifier)의 완전 결속**: 코드 해시(Git Commit SHA) + 데이터셋 해시(DVC md5) + 모델 가중치 해시(MLflow Run ID)가 삼위일체로 묶여 있어야만 사후 감리 추적성 보증
2. **이질적 영향(Disparate Impact)의 수학적 검증**: 보호 집단(여성)의 승인율을 비보호 집단(남성)의 승인율로 나눈 비율이 0.80(80% 규칙) 이상이어야 법적 알고리즘 차별 없음 입증
3. **설명가능성(XAI)의 필수성**: 딥러닝 블랙박스 판정 결과에 대해 SHAP(Shapley Additive Explanations) 수치를 산출하여 최종 사용자에게 "왜 대출이 거절되었는가"를 설명할 수 있어야 함
4. **환각률(Hallucination Rate) 벤치마크**: 생성형 AI 감리 시 사내 문서 DB와 LLM 답변 간의 코사인 유사도 및 문맥 충실도(Faithfulness) 지표를 측정하여 허위 정보 출력 차단
5. **인간 감독(Human-in-the-Loop)의 비상 개입**: AI 모델의 확신도(Confidence Score)가 70% 미만인 애매한 케이스는 자동으로 인간 심사역에게 이관(Fallback)되는 안전망 강제

#### 한줄 요약
- 위험 분류, 데이터 계보 실사, 불변 해시 학습 재현, 공정성/XAI 검증, MLOps 드리프트/HITL 확인 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전통적 소프트웨어 감리 vs AI 시스템 감리 비교**:
  - 전통적 SW 감리: 결정론적(Deterministic) 로직, 명세서와 코드의 1:1 일치성 검증.
  - AI 시스템 감리: 확률론적(Stochastic) 모델, 데이터 품질, 알고리즘 공정성, 드리프트 검증.

</details>

| 비교 항목 | 전통적 소프트웨어 감리 (Traditional IS Audit) | 인공지능 개발 사업 감리 (AI System Audit) |
|:---|:---|:---|
| **검증 핵심 철학** | **결정론적 로직 (입력 A ➔ 항상 결과 B)** | **확률론적 모델 (입력 A ➔ 확률적 추론 P(B\|A))** |
| **핵심 감리 대상** | **소스코드, 데이터베이스 설계서, 인터페이스** | **학습 데이터셋, 모델 가중치, MLOps 파이프라인** |
| **주요 품질 척도** | 구문/분기 커버리지, 기능 구현율, 응답시간 | **F1/AUC, 공정성 지표, XAI 설명도, 환각률** |
| **품질 변질 요인** | 소스코드 변경(버그 수정)에 의해서만 발생 | **시간 경과에 따른 런타임 데이터 드리프트 발생** |
| **형상 관리 기준** | Git 소스코드 커밋 버전 | **Git(코드) + DVC(데이터) + MLflow(모델) 삼위일체** |
| **주요 법적 기준** | 전자정부법, 소프트웨어 진흥법 | **ISO/IEC 42001, EU AI Act, NIST AI RMF** |

#### 한줄 요약
- 전통적 감리는 결정론적 코드 일치성, AI 감리는 확률론적 데이터 계보/공정성/드리프트 검증에 특화된다.

## Ⅶ. 결론

- 인공지능의 확률적 불확실성과 블랙박스 위험 속에서 기술적 신뢰성과 사회적 윤리성을 보증하는 최상위 IT 품질 공학인 **AI 개발 사업 특수 감리 체계**는 단순한 성능 평가를 넘어 신뢰할 수 있는 인공지능(Trustworthy AI)을 구현하는 핵심 나침반이며, 실무 구현 시 **ISO/IEC 42001 표준 기반의 전 생애주기 점검**, **DVC/Git/MLflow 결속을 통한 모델 재현성 입증**, **알고리즘 공정성 및 XAI 설명가능성 실사**, **MLOps 드리프트 감시와 인간 감독권(HITL) 확립**을 완성하여 최고 수준의 인공지능 품질 무결성과 안전한 사회적 안착을 완성

#### 한줄 요약
