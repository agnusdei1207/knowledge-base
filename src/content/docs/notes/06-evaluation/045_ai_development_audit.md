## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AI 개발 사업 감리(AI Audit)**: 데이터 구축, 모델 학습, 서빙 운영 전 주기에서 품질, 신뢰성, 공정성, 안전성을 독립 검증하는 전문 감리.
- **AI 신뢰성/윤리**: 데이터 편향 제거, 모델 설명가능성(XAI), 프라이버시 보호, 안전성 통제 체계.

</details>

- 정의/개념: 데이터 수집·정제부터 모델 학습, 평가, MLOps 배포 및 운영에 이르는 AI 전 생애주기에서 품질, 신뢰성, 공정성을 독립 점검하는 특수 감리 체계
- 배경/필요성: 전통적 코드 감리의 한계를 극복하고 **데이터 편향, 확률적 오류, 모델 드리프트 및 환각(Hallucination) 위험 예방** #### 한줄 요약

- 데이터 출처부터 **배포 후 감독·롤백**까지 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 계보(Data Lineage)**: 원천 데이터 수집 출처부터 정제, 가공, 라벨링, 학습 데이터셋 생성까지의 전 과정 추적성.
- **인간 감독(Human-in-the-Loop, HITL)**: 고위험 AI 의사결정 시 최종 승인 및 비상 중단 권한을 인간 관리자가 통제하는 체계.

</details>

- **데이터 계보·재현성** 기반 평가 증거
- 집단별 **공정성·적대적 강건성** 검증
- **모델 드리프트·인간 감독** 운영 통제

#### 한줄 요약

- 계보·재현·드리프트·**인간 감독** 증거 검증

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 카드(Model Card)**: 모델의 의도된 용도, 성능 지표, 한계점, 윤리적 고려사항을 표준 문서화한 명세서.
- **불변 식별자(Immutable ID)**: 데이터셋 버전(DVC), 소스 코드 커밋(Git), 모델 가중치(MLflow)를 일체화하여 고정한 해시값.

</details>

```text
AI 개발 사업 감리 4대 계층 아키텍처
├─ 목적/거버넌스: 오류 비용 산정 / ISO 42001, NIST AI RMF 정렬
├─ 데이터 품질: 출처 적법성 / 라벨링 정밀도 / 클래스 불균형 / 계보 추적
├─ 모델 신뢰성: 정량 성능(F1/AUC) / 재현성 / 공정성 / 적대적 강건성
└─ 서빙 및 MLOps: 데이터·개념 드리프트 감시 / 비상 롤백 / 인간 감독권
```

선의 의미: 비즈니스 목적 및 위험 정의 아래 데이터, 모델, 버전 증적, 운영 감독 책임을 연결하는 AI 개발 감리 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 목적•위험 | 오류 비용·피해 집단과 합격선 정의 |
| 데이터 | 출처·권리·대표성·**계보** 검증 |
| 모델 | **공정성·강건성·모델 카드** 검증 |
| 버전•증거 | **불변 식별자·재현성** 확보 |
| 운영•책임 | 드리프트 감시·중단 권한 명확화 |

#### 한줄 요약

- 위험별 **데이터·모델·버전·운영 책임** 검증

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **재현 시험(Reproducibility Test)**: 동일한 시드값, 하이퍼파라미터, 학습 데이터로 모델을 재학습했을 때 동일한 성능이 도출되는지 검증하는 절차.

</details>

```text
       발주기관
              │ 1. AI 서비스 위험 등급 및 오류 허용 한계 정의
              ▼
       감리인
              │ 2. 데이터 계보, 저작권, 라벨링 검수 증적 실사
              ▼
       모델 검증팀
              │ 3. 불변 식별자 기반 모델 학습 재현 및 공정성 시험
              ▼
       MLOps 실사
              │ 4. 드리프트 탐지 알림, 비상 중단, 롤백 절차 검증
              ▼
       감리보고서 통보
              │ 5. 잔여 편향 위험 보고 및 조건부 배포 승인
              ▼
        신뢰할 수 있는 AI 서비스 오픈
```

**동작 원리** 1. **위험 정의**: 서비스 오작동 시 재무적·사회적 피해 규모를 분석하여 핵심 품질 지표 설정
2. **데이터 감사**: 학습 데이터의 출처 적법성, 개인정보 비식별화, 데이터 누수(Data Leakage) 검증
3. **모델 재현**: 시드 고정 및 MLOps 파이프라인을 실행해 보고서상의 성능과 공정성 수치 재현
4. **운영 통제**: 배포 후 데이터 분포 변화(Data Drift) 감시 체계 및 즉각 롤백 기능 점검
5. **승인 판정**: 인간 감독 체계가 완비된 모델에 한해 최종 운영 배포 승인

#### 한줄 요약

- 오류 비용별 증거와 **감독·롤백 통제** 충족 후 배포

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 감리 vs 모델 감리 vs 운영 감리**: 학습 데이터 무결성(데이터), 알고리즘 품질 및 공정성(모델), 런타임 드리프트 및 안정성(운영)의 3단계 감리 분할.

</details>

| AI 감리 점검 영역 | 데이터 감리 (Data Audit) | 모델 감리 (Model Audit) | 운영 감리 (Operation Audit) |
|:---|:---|:---|:---|
| 적용 기준 | 데이터 수집 적법성, 라벨링 품질, 편향 검증 시 | 모델 아키텍처, 학습 파이프라인, 재현성 검증 시 | MLOps 배포, 모델 드리프트, 인간 감독 검증 시 |
| 핵심 특징 | 데이터 계보(Lineage), 클래스 불균형, 누수 탐지 | 정량 성능(F1/AUC), 공정성 지표, 적대적 강건성 | 실시간 성능 모니터링, 자동 재학습, 비상 롤백 |
| 한계 | 비정형 데이터 정제 및 저작권 확인의 난이도 | 블랙박스 딥러닝 모델의 설명가능성 한계 | 런타임 데이터 드리프트 및 환각 통제 한계 |

#### 한줄 요약

- 데이터·모델·운영별 **승인 책임** 분리

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터/개념 드리프트**: 운영 중 입력 데이터 분포가 변화하거나(Data Drift) 입력과 타깃 간의 관계가 변하여(Concept Drift) 모델 성능이 저하되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 집단별 **미탐**·**오탐** 편중 | 집단별 지표·인간 검토 | 차별·윤리 위험 억제 |
| 데이터·모델 버전 단절 | MLOps **불변 식별자** 결속 | 승인 근거 재현·추적 |
| 배포 후 **드리프트** | 임계치 알림·롤백 책임자 | 성능 붕괴 조기 회복 |
| 프롬프트 주입·환각 | 격리·RAG 근거 검증 | 생성형 AI 오용·오류 감축 |
| 지사별 위험 기준 불일치 | **ISO 42001·NIST AI RMF** 정렬 | 거버넌스 일관성 확보 |

#### 한줄 요약

- 고위험 AI는 집단별 **미탐과 인간 검토** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **AI 생애주기 거버넌스**: 설계부터 폐기까지 전 과정에서 설명 가능하고 공정하며 안전한 AI 운영을 보장하는 엔터프라이즈 프레임워크.

</details>

- AI 생애주기 전반에 걸친 **데이터 계보 검증, 모델 재현성 확보 및 인간 감독(HITL) 체계 수립** #### 한줄 요약

- **재현 시험·드리프트 감시·인간 감독** 충족 후 배포
