## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **벤치마크 테스트(BMT: Benchmark Test / ISO/IEC/IEEE 29119)**: 정보시스템 구축 및 솔루션 도입 시 다수의 공급업체(Vendor) 후보 제품(하드웨어, DBMS, APM, 보안 솔루션 등)을 대상으로, 완전히 통제되고 격리된 동일한 시험 환경에서 실제 업무 부하 시나리오와 평가 기준을 적용하여 기능성, 처리 성능(TPS/지연시간), 안정성, 자원 효율성을 객관적으로 측정·비교·선정하는 표준 평가 방법론.
- **제안서 카탈로그 수치 맹신 및 평가 공정성 훼손 결함(Catalog Trust & Evaluation Bias Defect)**: 공급업체의 마케팅 수치나 정형화된 규격서에만 의존하여 실제 운영 워크로드에서의 성능을 검증하지 않거나, 후보 제품별로 서로 다른 하드웨어 스펙 및 캐시 설정이 적용되어 평가 결과의 공정성과 재현성(Reproducibility)이 상실되는 구조적 결함.

</details>

- 정의/개념: 도입 솔루션의 기술적 우수성과 비즈니스 적합성을 객관적으로 입증하기 위해 **평가 기준 및 배점 가중치 사전 동결(Pre-freezing) $\rightarrow$ 독립된 공통 테스트베드(Testbed) 구축 $\rightarrow$ 잔여 캐시 초기화 및 블라인드 무작위 시험 실행 $\rightarrow$ 원시 로그(Raw Data) 기반 편차 및 민감도 분석(Sensitivity Analysis) $\rightarrow$ 최적 도입 제품 최종 확정** 을 집행하는 **표준화된 성능 비교 평가 프레임워크**
- 배경/필요성: 소프트웨어 진흥법 및 국가계약법상 공공/금융 IT 사업에서 특정 업체 특혜 시비를 차단하고, 수백억 규모의 인프라 투자에 대한 기술적 타당성과 감사 추적성(Auditability)을 확보하기 위해 BMT 방법론 필수화

#### 한줄 요약
- BMT는 동일 환경과 사전 동결된 규칙 하에 다수 후보 제품의 성능과 기능을 공정하게 비교 평가한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **BMT 공정 비교(Fair Comparison) 4대 절대 원칙**:
  - **동일 인프라 환경 (Identical Environment)**: 동일 CPU, RAM, 스토리지, 네트워크 대역폭 상에서 시험.
  - **동일 데이터셋 (Identical Dataset)**: 동일한 건수, 분포, 인덱스 구조를 가진 시험 데이터 적용.
  - **동일 부하 시나리오 (Identical Workload)**: 부하 발생기에서 동일한 VUser, Ramp-up, Think Time 주입.
  - **동일 판정 기준 (Pre-frozen Criteria)**: 시험 개시 전 확정된 평가 항목, 배점, 과락 기준 불변 유지.

</details>

- **평가 기준의 사전 동결(Pre-Freezing)**: 시험 개시 후 특정 업체에 유리하게 평가 항목이나 배점을 변경하는 행위를 원천 차단
- **선행 시험 캐시 잔류 효과 배제(Cache Eviction)**: 특정 제품이 먼저 수행되어 OS나 디스크 캐시에 데이터가 잔류하는 불공정성을 방지하기 위해 매 시험 전 시스템 재부팅 및 버퍼 캐시 강제 플러시(`echo 3 > /proc/sys/vm/drop_caches`) 수행
- **민감도 분석(Sensitivity Analysis) 기반 순위 안정성 검증**: 특정 평가 항목의 가중치 변동($\pm 10\%$) 시 최종 1위 순위가 뒤바뀌는지 시뮬레이션하여 평가 신뢰성 확보

#### 한줄 요약
- 공정 비교 4대 원칙, 평가 기준 사전 동결, 캐시 완전 초기화, 민감도 분석 및 감사 추적성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMT 방법론 4대 핵심 아키텍처 계층**:
  1. **Governance & Scoping**: 평가 목표 정의, RFP 요구사항 매핑, 평가 배점표 사전 동결.
  2. **Common Testbed Layer**: 격리된 전용 시험망, 운영 동급 데이터셋, 분산 부하 생성기.
  3. **Execution & Control Layer**: 시험 순서 무작위화, 캐시 초기화, 블라인드 테스트 집행.
  4. **Analytics & Audit Layer**: 원시 데이터(Raw Log) 수집, 통계 편차 분석, 최종 평가 보고서.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 기준 관리 및 거버넌스 계층 (Criteria Pre-Freezing Layer) ]         │
│  ├─ [ 평가 위원회 ] ➔ 평가 항목, 배점 가중치, 과락 기준 확정 및 서명   │
│  └─ [ 사전 공지 ] ➔ 모든 참여 벤더사에 BMT 시나리오 및 규칙 100% 사전 공개│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (공통 시험 환경 인계)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 독립 공통 테스트베드 계층 (Isolated Common Testbed) ]              │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 동일 인프라 및 데이터셋 ]       │ [ 분산 부하 발생기 (JMeter / k6) ]   │
│ ├─ 동일 스펙 서버 및 스토리지     │ ├─ 피크 TPS 및 동시 사용자 주입    │
│ └─ 1,000만 건 정합성 데이터 적재  │ └─ 실 운영 트랜잭션 믹스(Mix) 재현 │
└───────────────────────────────────┴─────────────────────────────────────┘
                                     │ (순서 무작위화 및 캐시 초기화)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 블라인드 공정 실행 계층 (Blinded Execution & Cache Eviction) ]     │
│  ├─ [ 환경 초기화 ] ➔ 매 시험 전 서버 재부팅 및 OS/DB 버퍼 캐시 플러시  │
│  └─ [ 순차 교차 실행 ] ➔ Vendor A ➔ Vendor B ➔ Vendor C (3회 반복 측정)  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (원시 계측 데이터 수집)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 분석, 통계 및 감사 판정 계층 (Raw Data Analytics & Audit Trail) ]  │
│  ├─ [ 원시 로그 대조 ] ➔ 조작 불가능한 타임스탬프 기반 TPS/p99 지연 확정 │
│  ├─ [ 민감도 분석 ] ➔ 가중치 변동 시뮬레이션으로 순위 왜곡 여부 검증   │
│  └─ [ 최종 우선협상대상 제품 확정 및 BMT 결과 감사 보고서 발행 ]        │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 평가 기준 사전 동결 후 공통 테스트베드에서 캐시 초기화 기반 블라인드 시험을 수행하고 원시 데이터를 분석하여 최종 순위를 확정하는 구조

| 프레임워크 컴포넌트 | 핵심 기능 및 역할 | 주요 산출물 및 기법 | 비고 |
|:---|:---|:---|:---|
| **평가 기준표** | 기능/비기능 요구사항 배점, 필수 합격선, 과락 기준 정의 | BMT 계획서, 가중치 평가표 | 사전 동결 |
| **공통 테스트베드** | 외부 간섭이 완전히 배제된 독립 물리/가상 시험 환경 | 전용 스위치, 격리 네트워크 | 동일 환경 |
| **데이터셋 생성기** | 운영 데이터의 볼륨과 통계적 분포를 모사한 시험 데이터 구축 | 더미 데이터셋, DB 스키마/인덱스 | 동일 데이터 |
| **부하 발생기** | 통제된 VUser 및 단계적 Ramp-up 부하를 주입하는 분산 노드 | JMeter, Locust, 부하 스크립트 | 동일 부하 |
| **감사 추적 원장** | 가공되지 않은 모니터링 원본 로그 및 설정 스냅샷 영구 보존 | Raw Log, APM 트레이스, SHA-256 | 감사 보증 |

#### 한줄 요약
- 평가 기준표(사전 동결), 공통 테스트베드, 데이터셋 생성기, 부하 발생기, 감사 추적 원장으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **BMT 수행 5단계 수명주기 프로세스 (ISO/IEC/IEEE 29119-2 준거)**:
  1. 계획 및 기준 동결: 평가 항목, 배점 가중치, 탈락 기준 확정 및 벤더 합의
  2. 공통 환경 구축: 동일 인프라 및 1,000만 건 시험 데이터 적재
  3. 시험 실행: 캐시 플러시 후 무작위 순서로 후보 제품별 3회 반복 부하 주입
  4. 데이터 분석: 평균 및 최댓값을 배제하고 3회 측정치의 중앙값/p99 지연 산출
  5. 최종 판정: 민감도 분석 및 TCO 비용 평가를 결합하여 최종 권고 제품 선정

</details>

```text
1. [계획 수립 및 기준 사전 동결]
    ├─ 대상 솔루션: 차세대 DBMS 도입 후보 3개사 (Vendor A, B, C)
    ├─ 평가 항목: 트랜잭션 처리량(40%), p99 응답시간(30%), 장애 페일오버 시간(30%)
    └─ [평가 배점표 확정 및 모든 참여 업체 서명 날인 (사후 변경 불가)]
            │
            ▼
2. [공통 테스트베드 및 데이터셋 구축]
    ├─ 독립된 10Gbps 전용 시험망 및 동일 Xeon 64코어 서버 클러스터 준비
    └─ [실제 운영 통계 기반 1,000만 건 데이터 생성 및 인덱스 100% 동일 구성]
            │
            ▼
3. [캐시 초기화 및 블라인드 반복 실행]
    ├─ 1회차: OS 재부팅 ➔ 캐시 플러시 ➔ Vendor A ➔ B ➔ C 순서로 5,000 TPS 2시간 부하 주입
    ├─ 2회차: 순서 셔플 (B ➔ C ➔ A), 3회차: 순서 셔플 (C ➔ A ➔ B)
    └─ [APM 및 OS 메트릭 원시 로그(Raw Data) 동시 수집]
            │
            ▼
4. [통계 분석 및 민감도 검증]
    ├─ 3회 반복 측정치에 대한 편차 분석(표준편차 3% 이내 확인) ➔ 중앙값 확정
    ├─ 가중치 $\pm 10\%$ 시뮬레이션 수행 ➔ Vendor A가 모든 시나리오에서 1위 유지 입증
    └─ [조작 불가능한 원시 데이터 로그를 첨부하여 감사 보고서 생성]
            │
            ▼
5. [최종 도입 솔루션 확정]
    ├─ 기술 BMT 점수(80%) + 가격 TCO 점수(20%) 종합 합산
    └─ [최고 득점 제품인 Vendor A를 최종 우선협상대상자로 선정]
```

**동작 원리**

1. **단일 변인 통제**: 솔루션 소프트웨어를 제외한 모든 인프라, 네트워크, 데이터, 부하 조건을 완벽히 고정하여 성능 차이의 원인이 오직 제품 자체에 있음을 증명
2. **외생 변수 제거**: 선행 시험에 따른 디스크 캐시 및 스왑 메모리 잔류 효과를 콜드 스타트(Cold-start) 플러시로 100% 제거
3. **통계적 반복 신뢰성**: 1회성 시험의 우연성을 배제하기 위해 최소 3회 이상 반복 측정하여 표준편차 범위 내의 신뢰 구간 데이터만 채택
4. **블라인드 평가(Blinded Evaluation)**: 분석관에게 제품명을 'Solution X, Y, Z'로 익명화하여 주관적 브랜드 선호도 개입 차단
5. **감사 가능성(Auditability)**: 평가의 전 과정(명령어 이력, 설정 파일, Raw 패킷 로그)을 위변조 불가능하게 아카이빙하여 법적 분쟁 완전 예방

#### 한줄 요약
- 기준 사전 동결, 공통 환경 구축, 캐시 플러시 반복 실행, 통계/민감도 분석, 최종 우선협상 제품 선정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **기술 검증 2대 방식 비교**:
  - 벤치마크 테스트 (BMT): 다수 상용 제품 간의 상대적 성능·기능 순위 비교 (경쟁 평가).
  - 개념 증명 (PoC: Proof of Concept): 신기술이나 특정 아키텍처의 기술적 실현 가능성 검증 (단일 타당성).

</details>

| 비교 항목 | 벤치마크 테스트 (BMT) | 개념 증명 (PoC: Proof of Concept) |
|:---|:---|:---|
| **주요 목적** | **다수 후보 제품 간의 성능/품질 객관적 우열 비교**| **단일 신기술의 비즈니스 구현 가능성 검증** |
| **평가 대상** | **복수의 상용 솔루션 (Vendor A vs B vs C)**| 특정 신기술 프로토타입 또는 단일 솔루션 |
| **수행 환경** | **운영 동급의 엄격히 통제된 공통 테스트베드**| 소규모 샌드박스 또는 개발 환경 |
| **평가 척도** | **정량적 수치 (TPS, p99 지연, 자원 사용률)** | 정성적/정량적 가능 여부 (Yes / No) |
| **결과 산출물** | **공식 종합 평가표, 순위 판정, 감사 보고서** | 기술 검증 보고서, 아키텍처 타당성 결과서 |
| **실무 적용 시점**| 솔루션 도입 최종 발주 및 우선협상대상자 선정 시| 프로젝트 초기 기획 및 아키텍처 기술 검토 시 |

#### 한줄 요약
- BMT는 다수 제품 간의 엄격한 경쟁 순위 평가, PoC는 단일 신기술의 구현 가능성 검증에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **BMT 실무 수행 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 평가 진행 중 특정 벤더의 로비나 이의 제기로 인해 **평가 항목이나 배점 가중치를 수정하여 탈락 업체가 소송을 제기하는 공정성 시비 발생** | **시험 개시 전 모든 참가 업체가 서명한 평가 기준표를 사전에 영구 동결(Pre-freezing)하고 사후 변경 원천 불허** | 평가 결과의 법적 공정성 및 감사 추적성 100% 확보 |
| 먼저 시험을 수행한 벤더 장비의 데이터가 디스크/OS 캐시에 남아 **후속 벤더 시험 시 성능이 20% 이상 높게 측정되는 불공정성 발생** | **매 시험 전 서버 하드웨어 완전 재부팅 및 OS 커널 캐시 플러시(`drop_caches`)를 강제하고 시험 순서 무작위 셔플** | 캐시 잔류에 의한 측정 편향 100% 원천 배제 |
| 특정 성능 항목(예: 단순 조회 TPS)의 배점이 70%로 과도하여 **복합 결제 트랜잭션 및 장애 복구 기능이 우수한 고품질 솔루션이 탈락** | **가중치를 $\pm 10\%$ 조정한 민감도 분석(Sensitivity Analysis)을 사전 수행하여 특정 항목 편향 없는 균형 배점표 설계** | 특정 지표 편향 방지 및 최적의 솔루션 선정 |

#### 한줄 요약
- 기준 사전 동결로 법적 공정성을 확보하고, 캐시 플러시로 편향을 없애며, 민감도 분석으로 균형 배점을 수립한다.

## Ⅶ. 결론

- 최적의 소프트웨어 및 하드웨어를 객관적 실측 데이터에 기반하여 공정하게 선정하는 엔터프라이즈 평가의 정수인 **BMT 방법론 체계**는 공급업체의 마케팅 과장을 걷어내고 실제 운영 안정성을 사전에 보증하는 필수 엔지니어링 절차이며, 실무 구현 시 **공정 비교 4대 원칙(동일 환경·데이터·부하·기준)의 엄격한 준수**, **평가 기준표의 사전 동결(Pre-freezing)**, **콜드 스타트 캐시 초기화 및 블라인드 반복 측정**, **원시 로그(Raw Data) 기반의 민감도 분석 및 감사 추적성 확보**를 완성하여 최고 수준의 기술적 투명성과 최적의 IT 솔루션 선정을 완성

#### 한줄 요약
- 공정 비교 4대 원칙과 기준 사전 동결 및 캐시 초기화를 통해 무결점 BMT 평가 체계를 완성한다.
