## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **초당 트랜잭션 수(Transactions Per Second, TPS)**: 1초 동안 성공적으로 완료한 비즈니스 거래 건수.
- **폐쇄형 부하 모델(Closed Workload Model)**: 사용자의 요청·응답·생각시간 반복 주기를 모사한 부하 모델.
- **처리율 산정(Throughput Estimation)**: 동시 사용자 수, 응답시간, 생각시간으로 초당 처리량을 도출하는 기법.

</details>

- 정의/개념: 동시 사용자 수, 응답시간, 생각시간을 기반으로 시스템의 초당 처리량($X=N/(R+Z)$)을 산출하는 기법
- 배경/필요성: 단순 회원 수만으로는 **실제 요구 TPS** 역산 불가

#### 한줄 요약

- $N$, $R$, $Z$로 **목표 TPS 산정** ## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **대화형 응답시간 법칙(Interactive Response Time Law)**: 폐쇄형 시스템에서 동시 사용자(N)와 처리량(X), 응답시간(R), 생각시간(Z)이 $N=X(R+Z)$를 만족한다는 법칙.
- **동시 사용자(Concurrent Users, N)**: 서비스 루프를 반복하며 시스템 부하를 유발하는 활성 사용자 수.
- **부하 보정(Load Calibration)**: 이론 처리량에 피크타임 집중률과 트랜잭션 비율을 반영하는 보정 작업.

</details>

- **대화형 응답시간 법칙** 기반 처리량 관계 산출
- 업무 TPS와 내부 API RPS를 분리 측정
- 피크·업무 비율을 **부하 보정** 대상 반영

#### 한줄 요약

- 생각시간 증가 시 동일 사용자 대비 **요구 TPS 감소** ## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **응답시간(Response Time, R)**: 요청 송신부터 결과 반환까지의 왕복 지연시간.
- **생각시간(Think Time, Z)**: 응답 수신 후 다음 요청 송신까지 사용자가 소비하는 대기시간.
- **처리량(Throughput, X)**: 단위 시간당 오류 없이 완료된 비즈니스 거래 건수.
- **업무 거래 경계(Business Transaction Boundary)**: 단일 비즈니스 완수를 위해 발생하는 API 호출의 묶음 경계.

</details>

```text
TPS 산정 구조
├─ 업무 거래 경계
├─ 동시 사용자 N
├─ 응답시간 R
├─ 생각시간 Z
└─ 처리량 X·피크 보정
```

선의 의미: 사용자 수, 응답시간, 생각시간, 처리량의 상호 산출 관계 구조.

| 구성요소 | 책임 |
|:---|:---|
| 업무 거래 경계 | 거래 TPS와 API RPS 분리 |
| 동시 사용자 N | **동시 사용자** 규모 측정 |
| 응답시간 R | 목표 **응답시간** 설정 |
| 생각시간 Z | 실제 **생각시간** 반영 |
| 처리량 X·피크 보정 | **처리량·피크 계수** 산출 |

#### 한줄 요약

- $X=N/(R+Z)$ 기반 **처리량·피크 용량 산출** ## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **사용자 요청 주기(User Request Cycle)**: 요청·응답·생각시간을 합친 반복 순환 구간.
- **피크 TPS 보정(Peak TPS Calibration)**: 일 평균 처리량에 피크 집중률을 반영하는 작업.

</details>

```text
업무 책임자
   │ 거래 경계·피크 비율 전달
   ▼
분석가·측정기
   │ 1. N·R·Z 측정 조건 확정
   │ 2. N·R·Z 표본 수집
   ▼
계산·검증기
   │ 3. X=N/(R+Z) 계산
   │ 4. 업무 비율·피크 TPS 보정
   ▼
목표 TPS·시험 부하 결과
```

**동작 원리** 1. **N·R·Z 측정 조건 확정**: 사용자 요청 주기 정의
2. **N·R·Z 표본 수집**: 동시성·주기 지연 수집
3. **X=N/(R+Z) 계산**: 폐쇄형 평균 TPS 산출
4. **업무 비율·피크 TPS 보정**: 피크 용량 결정

#### 한줄 요약

- 평균 TPS에 **업무 비율·피크 계수 보정** ## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **개방형 부하 모델(Open Workload Model)**: 시스템 처리 상태와 무관하게 사전 정의된 도착률로 요청을 주입하는 모델.
- **초당 요청 수(Requests Per Second, RPS)**: 개별 HTTP 및 API 엔드포인트의 초당 호출 횟수.

</details>

| 부하 모델 | 동시 사용자 모델 (폐쇄형 부하) | 요청률 기반 모델 (개방형 부하) |
|:---|:---|:---|
| 적용 기준 | 사람의 웹·앱 화면 조작 | B2B 및 마이크로서비스 간 API 호출 |
| 핵심 특징 | 사용자 **생각시간** 기반 순환 주기 모델 | 독립적 도착률 기반 연속 요청 주입 |
| 한계 | 생각시간 설정 오류 시 처리량 왜곡 | 시스템 포화 시 큐 누적으로 지연 급증 |

> 요약: 사용자 행동 기반 서비스에는 폐쇄형 모델을, 시스템 간 연계 통신에는 개방형 모델을 구분 적용.

#### 한줄 요약

- 사람은 폐쇄형, 기계 호출은 **개방형 모델 선택** ## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **피크 계수(Peak Factor)**: 일 평균 처리량 대비 최대 트래픽 시간대의 집중 배수.
- **경계 혼동(Boundary Confusion)**: 비즈니스 거래 TPS와 인프라 API RPS의 혼동.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사용자 생각시간 누락으로 인한 용량 과대 산정 | 실제 사용자 행동 기반 **생각시간** 실측치 반영 | 과잉 TPS 산정 및 인프라 과투자 방지 |
| 비즈니스 거래와 내부 API 단위 혼용 | **업무 거래와 내부 요청** 분리 모델링 | **경계 혼동** 방지 및 정확한 병목 분석 |
| 평균치 적용으로 피크 시간대 지연 열화 | 트래픽 집중도 기반 **피크 계수** 적용 | 최대 부하 시간대 안정적 처리 용량 확보 |

#### 한줄 요약

- 결제 TPS와 내부 API **RPS 분리 계측** ## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **부하 현실화(Load Realization)**: 실제 로그를 분석해 동시성·응답·생각시간을 테스트에 동기화하는 절차.

</details>

- 대화형 서비스는 $N/(R+Z)$, API 호출은 독립 도착률 기반 목표 부하 산정

#### 한줄 요약

- 운영 로그로 보정해 **과소 용량·과잉 투자 방지**
