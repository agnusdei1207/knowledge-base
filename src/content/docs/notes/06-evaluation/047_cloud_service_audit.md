## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **공동 책임 모델**: 서비스 모델에 따라 CSP와 이용자의 보안·운영 책임을 나눈 체계.
- **CSPM**: 클라우드 자원의 구성 오류와 보안 태세를 지속 탐지하는 도구.
- **출구 전략**: 계약 종료 시 서비스·데이터를 안전하게 이전·삭제하는 계획.

</details>

- 정의/개념: CSP와 이용자의 책임 영역을 증거로 검증하는 **클라우드 전문 감리**
- 배경/필요성: 클라우드 컴퓨팅 환경 전환 시 클라우드 서비스 제공자(CSP)의 보안 인증서(ISO 27017/27018, CSAP 등)에만 맹목적으로 의존할 경우, 공동 책임 모델(Shared Responsibility Model) 하에서 이용자(Customer)의 책임 영역인 IAM 권한 오설정, 공개 S3 버킷 방치, 고객 관리 키(KMS) 통제 부재 및 벤더 종속(Lock-in)에 따른 출구 전략(Exit Strategy) 부재로 인해 대규모 데이터 유출과 복구 불가 재난이 초래되는 구조적 한계가 발생함에 따라, 서비스 모델(IaaS, PaaS, SaaS)별 책임 분계선을 명확히 확정하고 클라우드 보안 태세 관리(CSPM) 및 코드형 인프라(IaC) 드리프트를 정밀 검증하는 클라우드 서비스 감리 체계를 도입하여 **이용자 보안 설정의 100% 실증 실사, Multi-AZ 기반 고가용성 복원력 보증 및 데이터 암호학적 영구 삭제와 안전한 이관을 보장하는 출구 거버넌스**를 달성할 필요

#### 한줄 요약
- 클라우드 감리는 공동 책임 경계와 이용자 설정·복원력·출구 전략을 검증한다.

## Ⅱ. 특징

- IaaS·PaaS·SaaS별 **공동 책임 분계**
- API로 자원 설정을 확인하는 **CSPM 전수 실사**
- 선언 코드와 실행 상태를 비교하는 **IaC 드리프트 검증**
- 고객 관리 키로 통제하는 **KMS 봉투 암호화**
- 인증 보고서로 CSP 통제를 보는 **간접 감사**
- 장애 주입으로 확인하는 **Multi-AZ 복원력**
- 이관과 파기를 포함하는 **출구 전략**

#### 한줄 요약
- 책임 분계, CSPM, IaC, 고객 키, 복원력, 출구 전략이 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── 클라우드 감리 체계 ──────────────┐
│                                               │
├── [책임·거버넌스]                             │
│   └── 서비스 모델 · RACI · 인증 · SLA         │
├── [IAM·네트워크]                              │
│   └── 최소 권한 · MFA · VPC · 보안그룹        │
├── [데이터·형상]                               │
│   └── KMS · 암호화 · IaC · 드리프트           │
└── [복원력·출구]                               │
    └── Multi-AZ · 백업 · 이관 · 영구 파기      │
```

| 구성요소 | 책임 |
|:---|:---|
| **책임·거버넌스** | CSP·이용자 책임과 SLA 확정 |
| **IAM·네트워크** | 접근 권한과 통신 경계 통제 |
| **데이터·형상** | 암호화 키와 IaC 일치성 검증 |
| **복원력·출구** | 장애 복구와 이전·파기 가능성 검증 |

#### 한줄 요약
- 책임·거버넌스 영역이 맨 앞에서 CSP와 이용자의 분계를 확정해야 뒤의 세 영역에서 무엇을 직접 실사하고 무엇을 인증 보고서로 갈음할지가 정해지며, 복원력·출구 영역은 계약 종료 시점에야 드러나는 종속 비용을 사전 검증으로 앞당긴다.

## Ⅳ. 흐름도

```text
[클라우드 서비스]
     │
     │ 1. 서비스 모델·책임 경계 확정
     ▼
[클라우드 감리팀]
     │ 2. CSP 인증·SLA 검증
     │ 3. 이용자 설정·권한 실사
     │ 4. IaC·KMS·복원력 시험
     │ 5. 데이터 이관·파기 검증
     ▼
[발주기관]
     │
     └──────── 승인 결과 반환
```

**동작 원리**

1. **서비스 모델·책임 경계 확정**: 계층별 CSP·이용자 RACI 명시
2. **CSP 인증·SLA 검증**: 보고서 범위·예외·유효기간 교차 확인
3. **이용자 설정·권한 실사**: IAM·스토리지·보안그룹 API 전수 조회
4. **IaC·KMS·복원력 시험**: 실행 상태·키 통제·절체 동작 검증
5. **데이터 이관·파기 검증**: 표준 형식 복구와 파기 증거 확인

#### 한줄 요약
- CSP 통제는 인증 보고서로 간접 확인하고 이용자 설정은 API 전수 실사로 직접 확인하는 지점에서 갈리며, 보고서의 범위와 예외를 짚지 않으면 감사 불가 영역이 사고 후 책임 공방 비용으로 되돌아온다.

## Ⅴ. 종류 및 비교

| 비교 항목 | IaaS 감리 | PaaS 감리 | SaaS 감리 |
|:---|:---|:---|:---|
| 이용자 책임 | **가장 넓은 범위** | 애플리케이션·데이터 중심 | 계정·데이터 중심 |
| 주요 대상 | OS·VPC·스토리지 | 런타임·관리형 DB·API | 권한·테넌트·데이터 |
| 설정 위험 | 패치·포트·버킷 공개 | 플랫폼 파라미터·인증 | 과도 권한·격리 실패 |
| 암호화 통제 | 볼륨·객체의 고객 키 | 관리형 저장소의 고객 키 | BYOK 지원 여부 |
| 출구 난도 | 이미지·데이터 이전 | 런타임·DB 변환 | **전용 형식 종속** |

#### 한줄 요약
- 서비스 추상화가 높을수록 이용자 책임은 줄고 출구 통제는 중요해진다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| CSP 인증을 이용자 보안까지 확대 해석 | 책임 경계별 **통제 소유자** 확인 |
| 공개 스토리지·과도한 IAM 권한 | CSPM 기반 **설정 전수 점검** |
| 콘솔 변경에 따른 IaC 불일치 | GitOps 기반 **드리프트 탐지·복구** |
| 고객 키의 권한 집중과 복구 불가 | 키 분리·백업·회전의 **KMS 통제** |
| 독점 API·데이터 형식의 종속 | 표준 형식의 **이관·복원 훈련** |

#### 한줄 요약
- 책임 소유, CSPM, 드리프트, 키 관리, 이관 훈련으로 위험을 통제한다.

## Ⅶ. 결론

- 클라우드 네이티브 환경에서 CSP와 이용자 간의 공동 책임을 명확히 구분하고 이용자 측의 아키텍처, 보안, 형상 및 데이터 주권을 객관적으로 검증하는 **클라우드 네이티브 아키텍처 및 책임 공유 검증(Cloud Service Audit / ISO 27017 & CSPM / Shared Responsibility & Exit Strategy)의 필수 감리 표준**으로 확고히 자리 잡았으며, 멀티/하이브리드 클라우드 전반의 지속적 감사 및 정책 기반 인프라 검증(Policy-as-Code)으로 진화하는 가운데, 실무 클라우드 서비스 감리 및 거버넌스 수립 시에는 **CSP 인증서 확인을 넘어 API 기반 CSPM 도구로 이용자 설정 및 IAM 최소 권한을 전수 실사, IaC 템플릿과 실행 클라우드 자원 간 형상 불일치(Drift) 자동 차단, 계약 종료 시 벤더 종속 탈출을 위한 표준 포맷 데이터 백업 및 암호학적 파기 증명 절차 수립**을 결합하여 완벽한 클라우드 보안성과 데이터 주권을 완성

#### 한줄 요약
- CSP 인증과 별개로 고객 설정·키·복구·출구 능력을 입증해야 한다.
