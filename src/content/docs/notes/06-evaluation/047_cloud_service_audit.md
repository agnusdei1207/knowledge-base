## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **클라우드 서비스 감리(Cloud Service Audit)**: IaaS, PaaS, SaaS 환경의 아키텍처 적합성, 보안, 가용성, 비용을 독립 검증하는 감리.
- **공동 책임 모델(Shared Responsibility Model)**: 클라우드 서비스 모델(IaaS/PaaS/SaaS)별 CSP와 이용자의 보안·운영 책임을 명확히 구분한 원칙.

</details>

- 정의/개념: IaaS, PaaS, SaaS 클라우드 서비스 모델별 공동 책임 모델(Shared Responsibility)을 바탕으로 아키텍처, 보안, 가용성, 출구 전략을 독립 검증하는 감리 체계
- 배경/필요성: CSP 제공자의 자체 인증서에만 의존하는 사각지대를 극복하고 **이용자 책임 영역(IAM, 데이터, 설정 오류)의 보안 및 안정성 확보** #### 한줄 요약

- 제공자 인증과 별개로 **이용자 통제 증거** 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IaC(Infrastructure as Code)**: Terraform, CloudFormation 등으로 인프라 구성을 코드로 정의하여 버전 관리하는 방식.
- **CSPM(Cloud Security Posture Management)**: 클라우드 설정 오류(Misconfiguration) 및 규정 위반을 자동 탐지하는 도구.

</details>

- IaaS·PaaS·SaaS별 **공유 책임** 확정
- **API 상태 대조·IaC** 기반 승인 구성 검증
- **재위탁자**까지 데이터·통제 책임 추적

#### 한줄 요약

- 모델과 무관하게 **계정·데이터는 이용자 책임** ## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IAM(Identity and Access Management)**: 사용자 계정, 역할, 최소 권한 원칙(Least Privilege)을 통제하는 클라우드 보안 핵심.
- **출구 전략(Exit Strategy)**: 서비스 종료 시 벤더 종속(Lock-in)을 방지하고 데이터를 안전하게 이관/삭제하는 계획.

</details>

```text
클라우드 서비스 감리 4대 통제 영역
├─ 책임 경계: IaaS/PaaS/SaaS 모델별 CSP vs 이용자 R&R 확정
├─ 구성 통제: VPC 네트워크 격리 / IAM 최소 권한 / IaC 형상 대조
├─ 데이터/보안: KMS 암호화 키 관리 / 테넌트 격리 / 백업 무결성
└─ 복원력/출구: Multi-AZ 장애 복구 훈련 / 이식성 / 영구 삭제 증명
```

선의 의미: 공동 책임 경계 아래 구성 통제, 데이터 보안, 운영 복원력 및 출구 전략을 연결하는 클라우드 서비스 감리 체계.

| 구성요소 | 책임 |
|:---|:---|
| 책임 경계 | 서비스 모델별 제공자·이용자 범위 확정 |
| 구성 통제 | **제어·데이터 평면·IAM** 설정 대조 |
| 데이터 통제 | **테넌트 격리·암호화·백업·삭제** |
| 운영 복원력 | 관측 가능성과 존 장애 복구 훈련 |
| 계약•출구 | **SLA·이식성·잔여 데이터 삭제** |

#### 한줄 요약

- 책임별 **구성·데이터·복구·출구 증거** 검증

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SOC 보고서**: CSP의 내부 통제 적절성을 제3자 회계법인이 검증한 보고서(SOC 1/2/3).

</details>

```text
       감리의뢰인
              │ 1. 클라우드 서비스 모델(IaaS/PaaS/SaaS) 및 감리 범위 확정
              ▼
       CSP(제공자) 증적 검토
              │ 2. CSAP, ISO 27017, SOC 2 공인 인증 보고서 확인
              ▼
       이용자 영역 실사
              │ 3. IAM 권한, 보안그룹, IaC 템플릿, KMS 암호화 설정 점검
              ▼
       복원력 및 출구 시험
              │ 4. Multi-AZ 절체 모의훈련 및 데이터 백업/이관 테스트
              ▼
       감리보고서 통보
              │ 5. 책임 공백 및 구성 결함 시정 권고
              ▼
        안전한 클라우드 서비스 운영
```

**동작 원리** 1. **책임 확정**: IaaS/PaaS/SaaS별로 CSP 통제 영역과 고객 관리 영역의 경계선 문서화
2. **CSP 간접 검증**: 물리 데이터센터 실사를 대신해 CSAP, SOC 2 등 제3자 감사 보고서의 유효성 점검
3. **고객 설정 실사**: CSPM 도구와 API 스캔을 통해 S3 버킷 공개, 불필요한 포트 개방 등 설정 오류 식별
4. **복원력 검증**: 가용 영역(AZ) 장애 시 오토스케일링 및 DB Failover 동작을 실환경에서 모의 검증
5. **출구 점검**: 계약 종료 시 데이터 반환 형식과 CSP 서버 내 잔여 데이터의 복구 불가능한 영구 삭제 절차 확인

#### 한줄 요약

- 제공자·이용자 증거 대조로 **책임 공백** 제거

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **서비스 모델별 책임**:
  - IaaS: 인프라(CSP) vs OS/미들웨어/앱/데이터(이용자)
  - PaaS: 인프라/OS/런타임(CSP) vs 앱/데이터(이용자)
  - SaaS: 인프라/OS/앱(CSP) vs 사용자 계정/데이터(이용자)

</details>

| 클라우드 서비스 모델 | IaaS (인프라 서비스) | PaaS (플랫폼 서비스) | SaaS (소프트웨어 서비스) |
|:---|:---|:---|:---|
| 적용 기준 | 가상 서버, 네트워크, 스토리지 직접 구성 시 | DB, 컨테이너, 미들웨어 플랫폼 활용 시 | 완성형 비즈니스 소프트웨어 서비스 구독 시 |
| 핵심 특징 | 이용자가 OS, 미들웨어, 보안그룹, 앱 직접 통제 | CSP가 런타임/OS 관리, 이용자는 앱/데이터 통제 | CSP가 앱 전체 관리, 이용자는 계정/데이터 통제 |
| 한계 | OS 보안 패치 및 인프라 구성 오류 부담 | 특정 CSP 플랫폼 종속성(Lock-in) 심화 | 테넌트 격리 불투명 및 세부 설정 통제 불가 |

#### 한줄 요약

- 상위 모델일수록 제공자 책임 증가, **계정·데이터는 공통** ## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 삭제 증명서**: 계약 해지 시 CSP가 보유하던 고객 데이터를 안전하게 파기했음을 증명하는 서약 문서.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제공자 인증 의존 | 공유 책임표·증거 소유자 명시 | 책임 공백 방지 |
| IaC와 실제의 **구성 편차** | API와 승인 IaC 상시 대조 | 런타임 준거 일치 |
| 계약 종료 후 잔여 데이터 | 이식 훈련·삭제 증명서 | 데이터 유출 위험 종결 |
| 온프레미스 기준의 오적용 | **ISO 27017·27018** 적용 | 클라우드 통제 적합성 |

#### 한줄 요약

- **IaC·실제 상태·출구 삭제** 활용 실행 증거로 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **클라우드 공유 거버넌스**: 클라우드 서비스 도입 시 책임 분계점을 명문화하고 지속적인 설정 감사(Audit)를 통해 클라우드 네이티브 보안을 완성하는 체계.

</details>

- 공동 책임 모델 기반 **이용자 통제 영역(IAM/암호화/백업) 실증 및 데이터 삭제 증명서 확인** #### 한줄 요약

- **이용자 통제 API 증거** 및 복구·삭제 시험 후 승인
