## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **클라우드 서비스 감리(Cloud Service Audit)**: IaaS, PaaS, SaaS 기반 클라우드 환경에서 구축·운영되는 정보시스템의 아키텍처 적합성, 보안, 가용성 및 비용 효율성을 검증하는 감리.
- **공동 책임 모델(Shared Responsibility Model)**: 클라우드 제공자(CSP)와 이용 기관 간의 보안 및 운영 책임 경계를 명확히 식별하여 감리 범위를 설정하는 핵심 원칙.
- **클라우드 아키텍처 적합성(Cloud Architecture Compliance)**: 오토스케일링, 멀티 AZ/리전 이중화, MSA 분산 구조의 적정성을 평가하는 기준.

</details>

- 정의/개념: 서비스 모델별 공유 책임과 증거를 검증하는 **클라우드 감리**
- 배경/필요성: 제공자 인증만으로는 **이용자 구성·책임 공백 확인 불가**

#### 한줄 요약
- 제공자 인증과 별개로 **이용자 통제 증거** 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **SLA 보증 및 비용 최적화(SLA & FinOps)**: CSP 제공 가용성 SLA 준수 여부와 유휴 자원 낭비를 방지하는 FinOps 거버넌스 체계 점검.
- **멀티테넌시 보안(Multi-tenancy Security)**: 공유 인프라 환경에서 가상화 계층 분리, 테넌트 간 데이터 격리, IAM 최소 권한 원칙 검증.
- **클라우드 종속성 방지(Lock-in Prevention)**: 특정 벤더 고유 서비스 과다 의존을 지양하고 오픈소스 및 컨테이너 표준을 통한 이식성 확보 여부 점검.
- **자동 확장성 및 탄력성(Elasticity & Auto-scaling)**: 부하 급증 시 자원이 유연하게 확장되고 정상 시 회수되는 탄력적 운영 구조 검증.

</details>

- IaaS·PaaS·SaaS별 **공유 책임** 확정
- **API 상태 대조·IaC**로 승인 구성 검증
- **재위탁자**까지 데이터·통제 책임 추적

#### 한줄 요약
- 모델과 무관하게 **계정·데이터는 이용자 책임**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **클라우드 인프라 계층(IaaS/PaaS Configuration)**: VPC 네트워크 격리, 서브넷 설계, 오토스케일링 그룹, 매니지드 데이터베이스 설정.
- **보안 및 접근 제어 계층(Cloud Security & IAM)**: 다중 인증(MFA), 역할 기반 접근 제어(RBAC), 보안 그룹(SG), 데이터 암호화(KMS).
- **운영 및 모니터링 계층(CloudOps & Observability)**: 중앙 집중식 로그 수집(CloudWatch/ELK), 분산 트레이싱, 비용 대시보드.

</details>

```text
                           [책임 경계]
                    /          |          |          \
             [구성 통제] [데이터 통제] [운영 복원력] [계약•출구]
```

선의 의미: 책임 경계 아래 구성·데이터·복원력·출구 통제

| 구성요소 | 책임 및 평가 초점 |
|:---|:---|
| 책임 경계 | 서비스 모델별 제공자·이용자 범위 확정 |
| 구성 통제 | **제어·데이터 평면·IAM** 설정 대조 |
| 데이터 통제 | **테넌트 격리·암호화·백업·삭제** |
| 운영 복원력 | 관측 가능성과 존 장애 복구 훈련 |
| 계약•출구 | **SLA·이식성·잔여 데이터 삭제** |

#### 한줄 요약
- 책임별 **구성·데이터·복구·출구 증거** 검증

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **클라우드 전환 계획 및 설계 점검(Architecture Audit)**: 클라우드 적합성 분석, 마이그레이션 전략, Multi-AZ 고가용성 설계를 검증하는 단계.
- **보안 및 접근 제어 점검(Security & IAM Audit)**: IAM 권한 남용, 보안 그룹 포트 개방, 데이터 저장/전송 구간 암호화 설정을 점검하는 단계.
- **SLA 및 비용 관리 체계 점검(SLA & FinOps Audit)**: 장애 복구 RTO/RPO 지표, 백업 자동화, 미사용 리소스 감축 정책을 확인하는 단계.
- **재난 복구 및 검수 지원(DR & Acceptance Audit)**: 클라우드 장애 시 다른 리전이나 가용 영역으로의 Failover 모의 테스트를 실증 검증하는 단계.

</details>

```text
              [이용자]
                  │ 클라우드 감리 요청
                  ▼
              [감리인]
                  │ 1. 책임•증거 소유자 확정
                  │   제공자 증거 요청
                  ▼
              [제공자]
                  │ 인증•장애•재위탁 증거
                  ▼
              [감리인]
                  │ 2. 제공자 통제 검증
                  │   이용자 통제 시험 요청
                  ▼
              [이용자]
                  │ 구성•복구•출구 시험 결과
                  ▼
              [감리인]
                  │ 3. 이용자 통제 검증
                  │ 4. 책임 공백•조치 판정
                  │
                  ▼
              [이용자]
```

### 동작 원리

1. **책임•증거 소유자 확정**: 모델별 통제·증거 주체 지정
2. **제공자 통제 검증**: 인증·장애·재위탁·SLA 증거 확인
3. **이용자 통제 검증**: 실제 구성·복구·출구 시험
4. **책임 공백•조치 판정**: 미배정 통제의 책임·기한 지정

#### 한줄 요약
- 제공자·이용자 증거 대조로 **책임 공백** 제거

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **온프레미스 감리(On-Premise Audit)**: 물리적 하드웨어 랙, 전력, 네트워크 케이블, OS 패치 등 물리 인프라 전반을 검증하는 방식.
- **클라우드 감리(Cloud Native Audit)**: 논리적 리소스 구성(IaC), API 정책, IAM 역할, 관리형 서비스의 탄력성을 검증하는 방식.

</details>

| 클라우드 서비스 계급 | 깡통 인프라 (IaaS) | 개발 플랫폼 (PaaS) | 구독형 완제품 (SaaS) |
|:---|:---|:---|:---|
| 감리 적용 기준 타깃 | OS·네트워크·앱·데이터 | 앱·데이터 | 계정·데이터·접근권한 |
| 가장 뼈 때리는 특징 | 이용자 **OS·보안그룹** 책임 | 제공자 플랫폼·이용자 앱 책임 | 제공자 앱·이용자 계정 책임 |
| 끔찍한 한계 및 부담 | 구성·패치 부담 | 종속성·키 관리 | 격리·통제 가시성 한계 |

#### 한줄 요약
- 상위 모델일수록 제공자 책임 증가, **계정·데이터는 공통**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CSP 감사 한계 극복(Third-party Audit Reports)**: 데이터센터 물리 실사가 불가능하므로 SOC 1/2/3, ISO 27017, CSAP 등 공인 제3자 인증 보고서로 대체 검증.
- **구성 오류(Misconfiguration) 탐지**: S3 버킷 퍼블릭 오픈 등 클라우드 보안 사고의 주원인인 설정 오류를 CSPM 도구로 자동 전수 점검.
- **클라우드 비용 누수 방지(Cost Governance)**: 약정 할인(RI/SP) 미적용, 과다 프로비저닝된 인스턴스를 식별하고 최적화 방안 권고.

</details>

| 제기된 실무 문제점 | 현장 적용 대책 | 기대되는 비즈니스 효과 |
|:---|:---|:---|
| **제공자 인증 의존** | 공유 책임표·증거 소유자 명시 | 책임 공백 방지 |
| IaC와 실제의 **구성 편차** | API와 승인 IaC 상시 대조 | 런타임 준거 일치 |
| 계약 종료 후 잔여 데이터 | 이식 훈련·삭제 증명서 | 데이터 유출 위험 종결 |
| 온프레미스 기준의 오적용 | **ISO 27017·27018** 적용 | 클라우드 통제 적합성 |

#### 한줄 요약
- **IaC·실제 상태·출구 삭제**를 실행 증거로 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **클라우드 네이티브 환경의 민첩하고 안전한 거버넌스(Cloud Governance)**: 공동 책임 모델을 기반으로 클라우드의 가용성, 보안, 비용 효율성을 종합 검증하여 안전한 디지털 전환을 지원하는 체계.

</details>

- 책임·실제 구성·복구·출구 삭제가 입증된 서비스만 승인

#### 한줄 요약
- **이용자 통제 API 증거**와 복구·삭제 시험 후 승인
