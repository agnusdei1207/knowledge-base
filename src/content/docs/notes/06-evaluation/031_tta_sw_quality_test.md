## 미리 알고가기

- **TTA(Telecommunications Technology Association)**: 정보통신 표준화와 시험·인증 서비스를 수행하는 한국정보통신기술협회
- **GS(Good Software) 인증**: 소프트웨어 제품의 품질을 실제 시험·평가해 적합성을 인증하는 제도
- **SW(Software)**: 컴퓨터가 기능을 수행하도록 하는 프로그램·데이터·관련 문서
- **제3자 시험(Third-Party Testing)**: 개발·구매 당사자와 독립된 기관이 수행하는 시험
- **시험 범위(Test Scope)**: 평가에 포함되는 제품 버전·기능·문서·플랫폼·운영 환경
- **시험 명세(Test Specification)**: 시험 대상·조건·절차·기대 결과를 정의한 문서
- **시험 케이스(Test Case)**: 입력·선행 조건·수행 단계·기대 결과를 구체화한 검증 단위
- **결함 리포트(Defect Report)**: 발견한 결함의 재현 조건·영향·증거를 기록한 문서
- **회귀시험(Regression Testing)**: 수정이 기존 정상 기능을 깨뜨리지 않았는지 다시 확인하는 시험
- **현장심사(On-Site Audit)**: 시험기관이 제품 개발·품질 관리의 현장 조건과 증거를 확인하는 심사
- **품질인증심의위원회**: 시험·현장심사 결과를 검토해 GS 인증 여부를 결정하는 위원회
- **시험결과서(Test Report)**: 시험 환경·항목·결과·결함·판정을 기록한 공식 문서
- **BMT(Benchmark Test)**: 같은 업무 조건에서 여러 제품의 성능·기능을 비교하는 시험
- **인수시험(Acceptance Testing)**: 납품 제품이 계약의 수용 기준을 충족하는지 발주자가 확인하는 시험
- **인증 범위(Certification Scope)**: 인증서가 유효한 제품 버전·기능·환경의 경계

## Ⅰ. 개요

- **정의/개념**: 제3자 시험으로 SW 품질 적합성을 인증한다
- **배경/필요성**: 객관적 시험 증거와 인증 범위를 확보한다

### 쉽게 이해하기 (학습용)

- 개발사가 품질이 좋다고 주장하는 대신 독립 시험기관이 실제 제품과 문서를 정해진 환경에서 시험하고 인증 여부를 판단한다.

## Ⅱ. 특징

- 제품·문서·시연은 시험 범위의 오해를 막는다
- 실제 제품 시험은 품질 주장의 객관성을 높인다
- 수정본 회귀시험은 결함 재발과 부작용을 찾는다
- 시험·현장심사 종합은 제품과 절차를 함께 검증한다
- 인증 범위 제한은 미시험 버전의 오용을 막는다

### 쉽게 이해하기 (학습용)

- 인증서가 회사 전체 소프트웨어를 보장하는 것이 아니라 시험한 특정 제품과 버전 및 환경에 대한 결과라는 점을 확인해야 한다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    A[신청 제품·문서] --> B[시험 범위·환경]
    B --> C[품질 시험·결함]
    C --> D[회귀시험·현장심사]
    D --> E[인증 심의·결과]
```

| 설계 요소 | 설명 |
|:---|:---|
| 신청 제품·문서 | 제품·버전·기능·매뉴얼 제출 |
| 시험 범위·환경 | 대상 플랫폼·항목·일정 확정 |
| 품질 시험·결함 | 시험 수행과 재현 증거 기록 |
| 회귀시험·현장심사 | 수정본과 품질 관리 현장 확인 |
| 인증 심의·결과 | 인증 여부와 범위·결과서 확정 |

> 요약: 제품 시험과 현장심사를 거쳐 인증 범위를 정한다

### 쉽게 이해하기 (학습용)

- 시험할 제품과 환경을 고정하고 결함을 찾고 수정본을 다시 시험한 뒤 현장 증거까지 포함해 위원회가 인증 범위를 결정한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant A as 신청자
    participant T as 시험기관
    participant R as 현장심사
    participant C as 인증심의위원회
    A->>T: 신청·상담 자료 제출
    T->>A: 시험 범위·계약 확정
    A->>T: 시험 제품 제출
    T-->>A: 결함 리포트·회귀시험
    T->>R: 현장심사 요청
    T->>C: 시험·심사 결과 상정
    C-->>A: 인증 결과·결과서 통보
```

| 절차 | 설명 |
|:---|:---|
| 신청·상담 자료 제출 | 매뉴얼·기능 목록·환경 제시 |
| 시험 범위·계약 확정 | 대상·수수료·일정·조건 합의 |
| 시험 제품 제출 | 고정 버전과 관련 문서 제공 |
| 결함 리포트·회귀시험 | 결함 수정과 영향 기능 재검증 |
| 현장심사 요청 | 개발·품질 관리 증거 확인 |
| 시험·심사 결과 상정 | 보고서를 위원회에 제출 |
| 인증 결과·결과서 통보 | 인증서·마크·시험결과서 전달 |

> 요약: 제품을 실제 시험·보완하고 심의로 인증을 결정한다.

### 쉽게 이해하기 (학습용)

- 신청 제품에서 결함을 찾아 고치고 다시 시험한 결과와 현장 품질 관리 증거를 위원회가 검토해 인증 여부를 정한다.

## Ⅴ. 종류 및 비교

| 비교축 | GS 인증 | BMT | 인수시험 |
|:---|:---|:---|:---|
| 핵심 특징 | 제품 품질 적합성의 제3자 인증 | 동일 조건의 제품 간 비교 | 계약 수용 기준의 납품 확인 |
| 적용 기준 | 인증서·마크와 공인 품질 증거 | 후보 제품 성능·기능 선정 | 개별 사업의 최종 인수 결정 |
| 주요 위험 | 인증 범위 밖 사용·변경 | 시험 조건 편향·순위 오용 | 계약 요구 누락·발주자 편향 |

> 요약: GS는 인증, BMT는 비교, 인수시험은 계약을 본다

### 쉽게 이해하기 (학습용)

- GS는 제품이 품질 기준에 맞는지 인증하고 BMT는 후보끼리 비교하며 인수시험은 납품물이 계약 약속을 지켰는지 확인한다.

## Ⅵ. 실무 사례

1. 인증서 버전과 도입 제품 버전을 대조한다
2. 운영 OS·DB 조합의 호환성을 추가 시험한다
3. 핵심 업무의 보안·성능 수용 기준을 별도 검증한다
4. 제품 업그레이드의 인증 범위 영향을 확인한다

### 쉽게 이해하기 (학습용)

- 사례 1은 같은 제품명이라도 시험하지 않은 새 버전을 기존 인증 제품으로 오인해 도입하지 않게 한다.
- 사례 2는 인증 시험 환경과 실제 서버 구성이 다를 때 설치·연계·장애 복구가 정상인지 확인한다.
- 사례 3은 GS 인증만으로 개별 사업의 높은 위험 조건까지 충족했다고 보지 않고 발주 수용선을 다시 시험한다.
- 사례 4는 운영체제·라이브러리·주요 기능 변경 뒤 기존 시험 증거가 그대로 유효한지 판단한다.

## Ⅶ. 결론

- GS 인증을 쓰면 제품 버전·시험 범위·운영 환경을 대조한다.

### 쉽게 이해하기 (학습용)

- GS 인증은 품질의 무조건적 보증서가 아니라 특정 제품 범위의 제3자 시험 결과이므로 실제 도입 조건과의 일치 여부를 확인해야 한다.
