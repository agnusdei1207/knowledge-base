## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **매케이브 순환 복잡도(McCabe's Cyclomatic Complexity, $V(G)$)**: 토머스 매케이브가 고안한 소프트웨어 정량 지표로, 소스 코드를 제어 흐름 그래프(CFG)로 변환한 뒤 내부에 존재하는 서로 독립적인 실행 경로(선형 독립 경로)의 개수를 수학적으로 측정하여 코드의 복잡도를 판별하는 구조 복잡도 지표이다.
- **제어 흐름 그래프(Control Flow Graph, CFG)**: 프로그램 내부에서 분기 없이 순차적으로 실행되는 기본 코드 블록(Basic Block)을 정점(Node)으로, 블록에서 블록으로 이어지는 제어의 물리적 이동 방향을 화살표 간선(Edge)으로 추상화하여 표현한 유향 그래프 모형이다.
- **선형 독립 경로 수(Number of Linearly Independent Paths)**: 소프트웨어를 실행할 때, 이전까지 실행되었던 어떤 테스트 경로 조합에서도 밟지 않았던 새로운 간선(분기)을 최소 하나 이상 무조건 포함하여 구성되는 논리적으로 독립된 최소 테스트 기준 경로의 개수이다.

</details>

- 정의/개념: CFG의 **선형 독립 경로 수**를 산출하는 복잡도 지표
- 배경/필요성: LOC만으로는 **제어 경로 누락 위험 판단 불가**

#### 한줄 요약
- 독립 경로 수로 **기본 경로 시험 하한** 산정

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **선형 독립 경로(Linearly Independent Path)**: 제어 흐름 그래프 안에서 시작 노드부터 종료 노드까지 관통하는 실행 궤적 중, 기존에 선택한 다른 어떤 궤적들에도 속하지 않은 고유한(Unique) 화살표를 적어도 한 번은 타는 실행 경로이다.
- **결정점(Decision Point/Predicate Node)**: if, switch-case, for, while, catch 구문과 같이 시스템의 실행 제어 흐름이 참/거짓 또는 여러 조건식 결과에 따라 둘 이상의 논리적 갈래로 나뉘어 빠져나가는 소스 코드 내의 분기점(Node)이다.
- **인지 복잡도(Cognitive Complexity)**: 수학적인 제어 경로 수(순환 복잡도)와 달리, 다중 중첩 구조나 복잡한 로직을 읽을 때 개발자(사람)가 이를 직관적으로 이해하고 유지보수하기 얼마나 심리적으로 어려운가를 별도의 가중치로 측정하는 현대적 보완 지표이다.
- **결정점 수+1 (Number of Decision Points + 1)**: 시작점과 종료점이 각각 하나로 단일하게 연결된 구조적 제어 흐름 그래프(단일 연결 CFG) 내부에서는, 복잡한 노드/간선 공식을 쓰지 않고 직관적인 조건문 분기 수(결정점 수)에 숫자 1을 더해 순환 복잡도를 빠르게 역산출해내는 동등성 원리이다.

</details>

![결정점 수에 따라 증가하는 순환 복잡도와 독립 경로 수](/study/diagrams/cyclomatic-complexity-paths.svg)

> 단일 연결 제어 흐름 그래프를 가정한 파란 선은 결정점이 하나 늘 때마다 \(V(G)\)와 기본 독립 경로 수가 하나씩 증가하는 \(V(G)=결정점 수+1\) 관계를 나타낸다.

- CFG의 간선·노드·연결 성분으로 **독립 경로** 산출
- 단일 CFG는 **결정점 수+1**로 계산
- 경로 수는 순환 복잡도, 이해 난도는 **인지 복잡도**

#### 한줄 요약
- 결정점 하나마다 **기본 독립 경로** 하나 증가

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **간선($E$, Edge)**: CFG 내에서 어떤 조건에 의해 기본 블록(명령어 그룹) 간에 물리적 제어와 실행 흐름이 순서대로 이동하고 넘겨짐을 잇는 화살표 연결선이다.
- **노드($N$, Node)**: 중간에 조건 분기나 예외 처리로 점프하지 않고 진입점부터 종료점까지 위에서 아래로 순차적으로 묶여서 한 덩어리로 실행되는 명령어들의 집합(기본 블록) 정점이다.
- **연결 성분($P$, Connected Component)**: 메인 프로그램과 외부 호출 라이브러리 함수처럼, 논리적 제어 흐름 경로가 서로 전혀 이어져 있지 않은 독립적이고 단절된 하위 제어 흐름 그래프들의 총개수이다.
- **기본 블록(Basic Block)**: 진입점은 오직 맨 첫 줄 명령어 하나뿐이고, 빠져나가는 출구 역시 맨 마지막 명령어 하나뿐이어서 무조건 일괄 순차 실행이 보장되는 쪼갤 수 없는 연속된 소스 코드 묶음이다.
- **임계값 정책(Threshold Policy)**: 순환 복잡도 수치가 특정 기준(예: 통상 10 이상, 15 이상 경고)을 초과하는 'Fat Function'에 대해, 자동 빌드를 실패시키거나 코드 리뷰 및 강제 리팩터링을 요구하도록 CI/CD 파이프라인에 세팅하는 품질 통제 규칙이다.

</details>

```text
순환 복잡도 분석 체계
├─ 분석 경계
├─ CFG
├─ 복잡도 산출
└─ 임계값 정책
```

선의 의미: 함수별 CFG와 복잡도를 임계값 정책에 연결

| 구성요소 | 책임 |
|:---|:---|
| 분석 경계 | 함수·메서드와 **연결 성분 $P$** 구분 |
| CFG | 기본 블록 **노드 $N$·간선 $E$** 표현 |
| 복잡도 산출 | $V(G)=E-N+2P$로 **독립 경로** 계산 |
| 임계값 정책 | 기준 초과 모듈을 개선 대상으로 지정 |

#### 한줄 요약
- CFG의 **독립 경로 수**로 임계값 초과 함수 식별

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **기본 경로 테스트(Basis Path Testing)**: 순환 복잡도 수식을 통해 산출된 최소한의 선형 독립 경로 모음(Basis Set)을 도출한 후, 그 각각의 고유 경로를 정확히 한 번씩 관통하도록 구체적 입력 파라미터를 설계하여 시스템 흐름을 검증하는 화이트박스 테스트 기법이다.
- **경로 집합(Basis Set of Paths)**: 무한 루프로 인해 발생할 수 있는 천문학적 횟수의 제어 궤적을 맹목적으로 다 열거하는 것이 아니라, 코드 안의 모든 조건 간선을 최소 한 번씩은 커버할 수 있도록 치밀하게 선별된 엑기스 최소 기준 경로 집합 모음이다.
- **리팩터링 우선순위(Refactoring Priority)**: 무조건 복잡도 수치가 높다고 갈아엎는 것이 아니라, 수치가 높으면서도 변경 빈도(Churn)가 잦거나 과거 버그 리포트 결함 이력이 쏠려 있고, 비즈니스 핵심(Core) 영역인 코드를 우선적으로 구조 개선 타깃으로 삼는 실무적 선별 순서이다.
- **CFG•순환 복잡도 산출**: 정적 분석 도구를 가동해 분석 타깃 경계 내 소스 파일들의 제어 흐름 그래프 토폴로지를 생성하고 $V(G)$ 지표를 자동 추출하는 진단 단계이다.
- **기본 경로•리팩터링 우선순위 결정**: 산출된 복잡도에 레거시 코드 변경 위험 요소를 결합 분석해, 당장 테스트 시나리오를 보완할 대상과 함수 쪼개기(리팩터링) 수술대에 올릴 대상을 선별하는 기획 단계이다.
- **독립 경로 시험•구조 개선**: 선별된 기준 경로에 맞춰 단위 테스트를 촘촘히 덧대어 짜거나, 응집도가 떨어지고 뚱뚱해진 고복잡도 함수를 다수의 단일 책임 함수로 분리해 내는 물리적 작업 단계이다.
- **경로 충족•복잡도 감소 검증**: 개선 작업 완료 후 코드 커버리지 계측 결과와 재측정된 순환 복잡도 수치가 목표 임계치 이하로 확실히 떨어졌는지 CI 대시보드 증거로 점검하는 마감 단계이다.

</details>

```text
정적분석도구
   │ 1. CFG•순환 복잡도 산출
   ▼
시험관리자
   │ 2. 기본 경로•리팩터링 우선순위 결정
   ▼
개발자
   │ 3. 독립 경로 시험•구조 개선
   ▼
시험관리자
   │ 4. 경로 충족•복잡도 감소 검증
```

### 동작 원리

1. **CFG•순환 복잡도 산출**: CFG와 독립 경로 수 계산
2. **기본 경로•리팩터링 우선순위 결정**: 경로 집합과 개선 순위 선정
3. **독립 경로 시험•구조 개선**: 기본 경로 시험 후 중첩 구조 개선
4. **경로 충족•복잡도 감소 검증**: 시험 증거와 복잡도 하락 확인

#### 한줄 요약

- 독립 경로별 시험 후 **고위험 함수 구조 개선**

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **순환 복잡도 적용(Cyclomatic Complexity Application)**: 테스트 엔지니어가 최소한 몇 개의 단위 테스트 케이스를 설계해야 이 함수 안의 모든 분기를 커버할 수 있는지 객관적 하한선(최소 기준 수) 기준을 도출할 때 활용하는 구조 중심 분석 방식이다.
- **인지 복잡도 적용(Cognitive Complexity Application)**: 유지보수 담당 개발자가 이 엉켜있는 다중 중첩 코드를 처음 접하고 로직을 추적할 때 얼마나 머리털이 빠지게 난해한지 심리적 가독성을 측정하여, 코드 리뷰 우선 타깃을 선정할 때 활용하는 사람 중심 분석 방식이다.
- **중첩 깊이(Nesting Depth)**: 하나의 함수 안에서 if, for 등의 제어 블록이 꼬리를 물고 안쪽으로 들어갈 때(Indent), 들여쓰기가 누적되어 중첩된 가장 최악의 최대 논리 단계를 수치로 나타낸 하위 뎁스 지표이다.
- **지표 선택(Metric Selection)**: 빠뜨림 없는 테스트 경로 확보를 원하면 순환 복잡도를, 후임자를 위한 소스 코드 이해 난도 개선을 원하면 인지 복잡도를, 과도한 들여쓰기로 인한 스파게티 코드 방지를 원하면 중첩 깊이로 통제 잣대를 구분하는 상황별 판단 기준이다.

</details>

| 복잡도 통제 지표 | 매케이브 순환 복잡도 (McCabe's) | 인지 복잡도 (Cognitive) | 중첩 깊이 (Nesting Depth) |
|:---|:---|:---|:---|
| 실무 적용 기준 | 시험 경로 하한 산정 | 코드 이해 난도 개선 | 들여쓰기 깊이 제한 |
| 핵심 측정 특징 | **선형 독립 경로 수** | 사람의 **이해 난도** | 최대 중첩 단계 수 |
| 한계 및 사각지대 | 데이터·외부 의존성 미반영 | 도구별 계산 규칙 상이 | 얕은 다중 분기 미반영 |

> 시험 경로·이해 난도·중첩 제한에 맞춰 **지표 선택**

#### 한줄 요약
- 시험은 순환, 가독성은 **인지 복잡도**로 판단

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **리팩터링(Refactoring)**: 사용자에게 제공되는 겉모습(기능과 외부 동작)은 단 1%도 변하지 않게 통제하면서, 수백 줄의 뚱뚱한 함수나 다중 중첩 분기 코드를 짧고 단일 책임을 갖는 서브 모듈로 분리 추출(Extract Method)하여 내부 유지보수성을 극대화하는 코드 재구성 활동이다.
- **회귀 테스트(Regression Test)**: 리팩터링으로 함수를 쪼개고 코드를 수정한 바로 직후, 기존에 잘 돌아가던 핵심 기능들이 구조 변경의 여파로 부작용을 일으키거나 은폐된 새 버그가 터지지 않고 완벽히 동일하게 동작하는지 확인하는 필수 보험 성격 테스트이다.
- **형식적 분할 방지(Prevention of Superficial Splitting)**: 순환 복잡도 점수가 임계값을 초과해 경고가 뜨자, 개발자가 단순히 점수만 깎아내기 위해 로직 연관성도 없는 코드를 기계적으로 툭툭 잘라 별도 함수로 넘겨버림으로써 시스템 전반의 응집도는 망치고 호출 결합도(Coupling)만 지옥으로 만드는 눈속임 꼼수 방지 조치이다.

</details>

| 제기된 문제 | 적용 대책 | 기대 효과 |
|:---|:---|:---|
| 고복잡도 함수의 미시험 경로 | 기본 경로별 단위 시험 | **회귀 테스트** 방어망 확보 |
| 임계값만으로 개선 대상 선택 | 변경·결함 이력 병행 | **리팩터링 우선순위** 확보 |
| 수치용 무의미한 함수 분할 | 결합도·인지 복잡도 검토 | **형식적 분할** 방지 |

#### 한줄 요약
- 기본 경로 **회귀시험 확보 후 리팩터링** 수행

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **경로 수와 테스트 수 관계(Relationship between Paths & Tests)**: $V(G)$ 공식으로 산출된 순환 복잡도 값은 결코 시스템의 절대 품질 점수가 아니라, 해당 함수가 품고 있는 모든 분기 로직을 검증하기 위해 최소한 몇 개의 화이트박스 테스트 묶음을 준비해야 하는지 알려주는 최소 기준선(Lower Bound)이라는 구조적 관계이다.
- **변경 위험 우선순위(Change Risk Prioritization)**: 순환 복잡도 숫자가 붉은색을 가리킨다고 무작정 뜯어고치는 것이 아니라, 해당 코드가 1년에 몇 번이나 업데이트되는지, 최근 버그 패치가 집중되었는지, 비즈니스상 돈이 걸린 핵심 영역인지를 종합 관찰해 리팩터링 대상을 타기팅하는 실전 관리 원칙이다.
- **시험•개선 결정(Test & Improvement Decision)**: 도출된 순환 복잡도 임계치에 근거해 당장 모자란 기본 경로 테스트 케이스 개수를 보충하고, 변경과 결함 발생이 잦으면서 수치가 높은 '고위험-고복잡도' 핫스팟 함수를 우선적으로 골라내 구조 개선 수술을 단행하는 엔지니어링 의사 판단이다.
