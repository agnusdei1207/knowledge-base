## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **병목**: 전체 처리량을 제한하거나 종단 응답시간을 지배하는 자원•구간이다.
- **임계 경로**: 여러 처리 구간 중 종단 응답시간을 결정하는 가장 긴 실행 경로이다.
- **병목 분석**: 처리량과 응답시간을 제한하는 자원•호출 경로•대기 구간을 측정해 임계 원인을 식별하는 성능 진단 활동이다.

</details>

- 정의/개념: 처리량•응답시간을 제한하는 **병목** 자원•경로를 찾는 **병목 분석**이다.
- 배경/필요성: 평균 사용률만으로는 대기와 임계 경로의 원인을 식별할 수 없다.

#### 한줄 요약

- 여러 관 중 가장 좁은 관이 전체 유량을 정하듯 포화 구간이 성능을 제한하는 것이 핵심이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **포화**: 자원이 즉시 처리하지 못한 작업이 대기열에 쌓인 상태이다.
- **상관 분석**: 요청 지연과 자원 포화를 같은 시간축에서 연결해 원인 관계를 찾는 분석이다.
- **병목 이동 검증**: 한 구간을 개선한 뒤 부하곡선을 다시 측정해 다음 제한 자원과 전체 성능 변화를 확인하는 과정이다.

</details>

- **상관 분석**으로 요청 지연과 **포화**를 같은 시간축에 연결한다.
- 자원과 서비스를 양방향으로 진단한다.
- **병목 이동 검증**으로 개선 전후 부하곡선을 비교한다.

#### 한줄 요약
- 느린 시간대의 요청 경로와 자원 대기열을 겹쳐 실제로 막힌 지점을 찾습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **USE(Utilization, Saturation, Errors)**: 자원별 이용률•포화도•오류를 점검하는 방법론이다.
- **RED(Requests, Errors, Duration)**: 서비스별 요청률•오류율•처리시간을 점검하는 방법론이다.

</details>

```text
병목 분석 체계
├─ 업무 부하•기준선
├─ 관측 증거
│  ├─ 서비스 RED 지표
│  ├─ 자원 USE 지표
│  └─ 추적•프로파일 증거
└─ 상관 분석기
```

가지의 의미: 기준 부하에서 수집한 서비스•자원•경로 증거의 분석 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 업무 부하•기준선 | 요청률•동시성•정상 성능 확정 |
| 서비스 RED 지표 | **RED** 지표 집계 |
| 자원 USE 지표 | **USE** 지표 집계 |
| 추적•프로파일 증거 | **임계 경로**•호출•핫스폿 연결 |
| 상관 분석기 | RED•USE•추적 증거로 후보 도출 |

#### 한줄 요약
- 자원 지표와 트랜잭션 추적 데이터를 결합하여 어떤 자원의 대기열이 성능을 제약하는지 판별합니다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **재현 조건**: 병목 후보의 전후 결과를 비교할 수 있도록 요청률•데이터•환경을 동일하게 고정한 시험 조건이다.
- **기준 부하 실행**: 요청률•데이터•환경을 고정해 비교 기준을 만드는 단계이다.
- **요청 추적•자원 지표 수집**: 종단 지연과 자원 이용률•포화•오류를 함께 모으는 단계이다.
- **USE•RED 지표 상관 분석**: 서비스 지연과 자원 포화를 동일 시간축으로 연결하는 단계이다.
- **병목 후보 검증**: 한 요인만 변경한 뒤 같은 부하로 성능 변화를 재측정하는 단계이다.

</details>

```text
분석가
   │ 재현 조건 확정
   ▼
부하 도구
   │ 1. 기준 부하 실행
   ▼
시험 대상·자원 수집기
   │ 2. 요청 추적·자원 지표 수집
   │ 3. USE·RED 지표 상관 분석
   ▼
검증 책임자
   │ 4. 병목 후보 검증
   ▼
개선 전후 처리량·지연 결과
```

### 동작 원리

1. **기준 부하 실행**: **재현 조건**에 따라 **기준 부하 실행**을 수행한다.
2. **요청 추적•자원 지표 수집**: **요청 추적•자원 지표 수집**으로 종단 지연과 USE 지표를 모은다.
3. **USE•RED 지표 상관 분석**: **USE•RED 지표 상관 분석**으로 지연과 포화를 연결한다.
4. **병목 후보 검증**: **병목 후보 검증**에서 단일 요인 변경 후 재측정한다.

#### 한줄 요약
- 지연이 발생한 시스템에서 자원 임계치를 확인하고, 포화도 검증을 거쳐 개선 효과를 재측정합니다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **자원 병목**: CPU•메모리•디스크•네트워크의 이용률과 대기 때문에 성능이 제한되는 상태이다.
- **DB(Database)**: 구조화 데이터를 저장•관리하는 데이터베이스이다.
- **구간 병목**: 특정 서비스•DB 호출이 종단 지연을 지배하는 상태이다.
- **자원•서비스 연계 분석**: 자원 중심 USE 방법론과 서비스 중심 RED 방법론을 함께 적용해 요청 지연의 내부 원인을 연결하는 방식이다.

</details>

| 병목 분석법 | USE 방법론 | RED 방법론 |
|:---|:---|:---|
| 적용 기준 | 서버 내부의 **자원 병목** 진단 | **DB** 호출 등 **구간 병목** 진단 |
| 핵심 특징 | **USE**로 자원 상태 분석 | **RED**로 서비스 상태 분석 |
| 한계 | 요청 경로 누락 | 내부 자원 원인 누락 |

> 요약: **자원•서비스 연계 분석**으로 USE와 RED를 결합한다.

#### 한줄 요약
- 인프라 자원의 포화도를 측정하는 기법과 사용자 요청 상태를 분석하는 기법을 조합해 병목을 찾습니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **부하곡선**: 부하 증가에 따른 처리량•응답시간•오류•자원 사용 변화를 함께 나타낸 곡선이다.
- **병목 이동**: 한 자원을 개선한 뒤 다음으로 제한적인 자원이나 구간이 새 병목이 되는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사용률만 확인해 대기 원인 누락 | **USE**로 이용률•포화도•오류 측정 | 포화 자원 식별 |
| 평균 지연만 확인해 구간 누락 | **RED**로 요청률•오류율•시간 측정 | 비정상 경로 식별 |
| 한 자원 개선 후 **병목 이동** 미검증 | **부하곡선** 재측정 | 다음 병목 확인 |

#### 한줄 요약
- 사용률만 보지 않고 대기열과 오류가 함께 늘어난 서버 자원을 찾습니다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **가설 검증**: 관측값으로 병목 후보를 세우고 한 번에 한 요인을 변경하여 개선 전후를 비교하는 절차이다.
- **개선 우선순위**: 임계 경로에서 포화와 대기열이 처리량을 제한한다는 증거가 확인된 자원을 먼저 개선하는 결정이다.

</details>

- **가설 검증** 후 **개선 우선순위**에 따라 임계 경로의 포화 자원을 먼저 개선한다.

#### 한줄 요약
- 가장 느린 구간과 가득 찬 자원을 파악해 전체 시스템의 처리 용량을 안전하게 늘립니다.
