## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **자동 페일오버 및 페일백(Auto Failover & Failback)**:
  - **자동 페일오버 (Auto Failover)**: 주 운영 시스템(Primary)의 하드웨어 고장, 커널 패닉, 서비스 먹통 발생 시 오케스트레이터가 이를 1초 내에 감지하고, 구 마스터를 격리(STONITH)한 후 대기 시스템(Standby)을 신규 마스터로 자동 승격하여 가상 IP(VIP)를 인계함으로써 RTO를 극소화하는 무인 장애 복구 기술.
  - **안전한 페일백 (Safe Failback)**: 장애가 발생했던 원래의 주 시스템이 수리 및 정상화된 후, 페일오버 기간 동안 대기 노드에 누적된 최신 변경 데이터를 역동기화(Differential Sync)하여 정합성을 맞춘 뒤 주 역할을 안전하게 회수하는 원상 복구 절차.
- **플래핑 진동 및 복귀 시 데이터 역전 손실 결함 (Flapping & Failback Overwrite Defect)**: 일시적인 네트워크 지연에 반응하여 마스터 권한이 좌우로 수 초마다 핑퐁 전환(Flapping)되어 시스템이 마비되거나, 페일백 시 구 마스터의 과거 데이터가 신규 마스터의 최신 데이터를 덮어써서 최신 트랜잭션이 영구 소실되는 구조적 결함.

</details>

- 정의/개념: 무중단 가용성과 데이터 정합성을 동시에 달성하기 위해 **다계층 헬스체크 및 쿼럼 합의 $\rightarrow$ 히스테리시스 유예 타이머 기반 플래핑 방지 $\rightarrow$ STONITH 펜싱 및 Standby 마스터 승격(Auto Failover) $\rightarrow$ LSN(로그 시퀀스 번호) 기반 차분 역동기화 $\rightarrow$ 야간 점진적 통제 페일백(Safe Failback)** 을 집행하는 **양방향 고가용성 제어 체계**
- 배경/필요성: 수동 개입에 의존하는 페일오버는 RTO(목표 복구 시간) 15분을 초과하여 대규모 비즈니스 손실을 유발하되, 페일백은 데이터 정합성 검증이 필수적이므로 자동화와 통제된 절차의 최적 결합 요구

#### 한줄 요약
- 자동 페일오버는 신속한 무인 장애 전환(RTO 극소화)을 수행하고, 페일백은 역동기화 검증 후 안전한 원상 복귀를 집행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **페일오버/페일백 3대 핵심 엔지니어링 메커니즘**:
  - **히스테리시스 유예 타이머 (Hysteresis Dwell Timer)**: 일시적 네트워크 플리커(Flicker) 시 즉각 전환하지 않고 일정 시간(예: 3회 연속 실패, 5초) 대기하여 플래핑 방지.
  - **가상 IP 플로팅 (Gratuitous ARP VIP Takeover)**: DNS 캐시 갱신 지연 없이 L2/L3 네트워크 레벨에서 ARP 패킷을 브로드캐스팅하여 클라이언트 커넥션을 즉시 신규 마스터로 리디렉션.
  - **LSN 기반 차분 역복제 (Log Sequence Number Catch-up)**: 페일백 시 전체 DB를 재복사하지 않고 장애 기간 동안 발생한 트랜잭션 로그 델타(Delta)만 고속 역동기화.

</details>

- **비대칭 운영 정책(Asymmetric Policy)**: 페일오버는 RTO 단축을 위해 100% 무인 자동화(Auto)로 실행하고, 페일백은 데이터 무결성 검증을 위해 관리자 승인 기반 수동/반자동(Manual/Controlled)으로 실행
- **플래핑(Flapping) 원천 억제**: 마스터 노드가 죽었다 살아나기를 반복할 때 클러스터가 요동치지 않도록 장애 노드를 즉시 클러스터에서 퇴출(Quarantine)
- **페일백 시 데이터 역전 방지**: 구 마스터가 복구되어 재기동될 때 스스로 마스터로 부팅되지 못하도록 `read-only` 또는 `standby` 모드로 강제 기동

#### 한줄 요약
- 신속 무인 페일오버, 관리자 통제 페일백, 플래핑 방지 유예 타이머, LSN 차분 역동기화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자동 페일오버/페일백 4대 아키텍처 계층**:
  1. **Health-check & Quorum Layer**: L4/L7 헬스체크 프로브, Keepalived, Corosync.
  2. **Fencing & Isolation Layer**: IPMI STONITH, SCSI-3 PR, 전원 차단기.
  3. **Traffic Switchover Layer**: Gratuitous ARP, VIP Floating, GSLB Anycast.
  4. **Replication & Catch-up Layer**: WAL/Binlog 리플레이 엔진 (`pg_rewind`, MySQL Clone).

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 정상 가동 및 실시간 순방향 동기화 (Active ➔ Standby) ]            │
│  ├─ [ Node 1 (Primary: VIP 10.0.0.10) ] ➔ 클라이언트 트랜잭션 처리     │
│  └─ [ Node 2 (Standby: Read-only) ] ◄──(WAL 실시간 순방향 복제)────────┤
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (Node 1 장애 발생 ➔ Auto Failover 가동)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 자동 페일오버 파이프라인 (Auto Failover Execution) ]               │
│  ├─ 1. [ 헬스체크 3회 실패 감지 ] ➔ 유예 타이머(3초) 경과 후 장애 확정  │
│  ├─ 2. [ STONITH 펜싱 ] ➔ Node 1의 IPMI 전원 강제 차단 (스플릿 방어)  │
│  ├─ 3. [ 마스터 승격 ] ➔ Node 2를 Read-Write Primary로 승격            │
│  └─ 4. [ VIP 플로팅 ] ➔ Gratuitous ARP로 VIP(10.0.0.10)를 Node 2로 인계 │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (Node 1 하드웨어 수리 후 Safe Failback)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 안전한 원상 복구 및 역동기화 파이프라인 (Safe Failback Execution) ]│
│  ├─ 1. [ Standby 기동 ] ➔ Node 1을 Read-only Standby 모드로 안전 기동 │
│  ├─ 2. [ LSN 차분 역복제 ] ➔ Node 2 ➔ Node 1으로 변경 트랜잭션 역동기화 │
│  ├─ 3. [ 복제 지연 0초 확인 ] ➔ LSN 일치 확인 및 관리자 페일백 승인    │
│  └─ 4. [ 야간 점진 전환 ] ➔ 점검 윈도우에 VIP를 Node 1으로 안전 회수   │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 장애 시 Node 2로 자동 페일오버된 후, Node 1 수리 시 역동기화를 거쳐 관리자 승인 하에 안전하게 페일백하는 양방향 구조

| 컴포넌트 | 핵심 기능 및 역할 | 주요 프로토콜/기술 | 비고 |
|:---|:---|:---|:---|
| **헬스체크 감시기** | TCP 포트, HTTP 200, SQL 질의 다계층 응답 시간 감시 | Prometheus Blackbox, Keepalived Check | Detection |
| **장애 격리 펜싱** | 구 마스터의 전원 강제 차단 및 잔여 스토리지 쓰기 격리 | IPMI STONITH, SCSI-3 PR | Isolation |
| **VIP 스위처** | 단일 IP 주소를 클러스터 노드 간 0.1초 만에 플로팅 이전 | Gratuitous ARP (GARP), VRRP | Routing |
| **차분 역복제 엔진** | 페일오버 기간 동안 발생한 변경분만 역방향 동기화 | `pg_rewind`, MySQL Group Replication | Sync |
| **페일백 제어기** | 복제 지연(Replication Lag)이 0일 때만 스위칭 허용 | Pacemaker Maintenance Mode, MHA CLI | Governance |

#### 한줄 요약
- 다계층 헬스체크, STONITH 펜싱, GARP VIP 플로팅, LSN 차분 역복제 엔진, 페일백 제어기로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 페일오버 및 안전 페일백 5단계 전체 수명주기**:
  1. Node 1(Active) 장애 발생 시 3회 헬스체크 타임아웃 감지
  2. STONITH 펜싱으로 Node 1 전원 차단 후 Node 2(Standby)를 Primary로 자동 승격
  3. VIP 플로팅 및 트래픽 정상 수용 (총 RTO 5초 달성)
  4. Node 1 부품 교체 후 Standby 역할로 안전 기동 및 Node 2로부터 LSN 역동기화
  5. 데이터 복제 지연 0초 확인 후 야간 점검 시간에 Node 1으로 점진 페일백 완료

</details>

```text
1. [Node 1 장애 발생 및 감지]
    ├─ Node 1 메인보드 고장으로 전원 다운
    ├─ 1초 주기 헬스체크 프로브 3회 연속 실패 (소요 3초)
    └─ [오케스트레이터가 'Primary Failure' 확정 판정]
            │
            ▼
2. [자동 페일오버 (Auto Failover)]
    ├─ Node 1의 IPMI 관리 포트로 STONITH 전원 강제 차단 명령 전송
    ├─ Node 2를 Read-Write Master로 승격
    └─ [ARP 패킷 발송으로 VIP(10.0.0.10)를 Node 2에 바인딩 ➔ 트래픽 정상 수용]
            │
            ▼
3. [Node 1 수리 및 Standby 복귀]
    ├─ 엔지니어가 Node 1 메인보드 교체 완료
    ├─ Node 1 기동 시 마스터 승격을 원천 차단하고 `Standby Mode`로 강제 시작
    └─ [Node 1 ➔ Node 2에 연결하여 최신 트랜잭션 역복제 요청]
            │
            ▼
4. [LSN 차분 역동기화 (Catch-up)]
    ├─ 페일오버 기간 동안 Node 2에서 생성된 100만 건의 트랜잭션 WAL 수신
    ├─ Node 1이 WAL 로그를 순차 리플레이(Replay)하여 로컬 데이터베이스 갱신
    └─ [복제 지연(Replication Lag)이 0ms에 도달함을 확인 (데이터 정합성 100%)]
            │
            ▼
5. [안전한 통제 페일백 (Safe Failback)]
    ├─ 야간 트래픽 최저 시간대(03:00)에 관리자 페일백 명령어 승인 실행
    ├─ Node 2를 잠시 Read-only로 전환 ➔ 잔여 큐 플러시 ➔ VIP를 Node 1으로 원상 복귀
    └─ [Node 1이 다시 Primary, Node 2가 Standby 상태로 완전 복원 완료]
```

**동작 원리**

1. **무인화(Auto)와 통제(Manual)의 분리**: 긴급 상황에서의 페일오버는 자동화하여 RTO를 5초로 줄이고, 평온한 상황에서의 페일백은 인간 검증을 거쳐 데이터 안전성 확보
2. **히스테리시스 타이머의 감쇠(Damping)**: 네트워크 순간 지연(1초)으로 인한 오작동을 막기 위해 최소 3초 이상의 지속 장애를 확인한 후 페일오버 트리거
3. **GARP(Gratuitous ARP)의 고속 라우팅 갱신**: 네트워크 스위치의 MAC 테이블을 즉시 갱신하여 클라이언트의 TCP 재연결이 0.1초 내에 신규 마스터로 라우팅
4. **LSN(Log Sequence Number) 역추적**: 분기된 데이터 블록을 포렌식 검증하고, 마스터가 변경된 시점 이후의 트랜잭션만 선별 역복제하여 다운타임 없는 복귀 달성
5. **무중단 롤링 페일백**: 페일백 시에도 커넥션 드레이닝(Connection Draining)을 적용하여 기존 처리 중인 트랜잭션을 안전하게 완료한 후 세션을 이관

#### 한줄 요약
- 장애 감지, STONITH 차단 및 Standby 자동 승격, Node 1 수리 후 Standby 기동, LSN 차분 역동기화, 관리자 승인 야간 페일백 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페일오버/페일백 2대 단계 특성 비교**:
  - 자동 페일오버: 긴급 장애 발생 시 작동 (신속성, 무인화, RTO 최우선).
  - 통제된 페일백: 시스템 수리 완료 후 작동 (안전성, 정합성, RPO 최우선).

</details>

| 비교 항목 | 자동 페일오버 (Auto Failover) | 통제된 안전 페일백 (Safe Failback) |
|:---|:---|:---|
| **실행 트리거** | **주 노드 고장 감지 시 자동 발동** | **주 노드 수리 및 데이터 역동기화 완료 후 관리자 승인**|
| **최우선 목표** | **서비스 중단 시간(RTO) 극소화 (가용성)**| **데이터 정합성 및 안전한 원상 복구 (일관성)**|
| **실행 주체** | **클러스터 오케스트레이터 (무인 자동화)**| **SRE 운영 엔지니어 (사전 승인 통제)** |
| **주요 위험 요소**| 일시적 지연 오판에 의한 플래핑(Flapping)| 과거 데이터로 최신 데이터 덮어쓰기 (Data Overwrite)|
| **핵심 기술** | **STONITH 펜싱, Gratuitous ARP VIP** | **LSN 차분 동기화 (`pg_rewind`), 커넥션 드레이닝**|
| **권고 실행 시점**| 장애 발생 즉시 (24시간 상시) | **야간 점검 윈도우 또는 트래픽 최저 시간대** |

#### 한줄 요약
- 자동 페일오버는 가용성(RTO) 중심의 즉각 무인 실행, 페일백은 일관성(RPO) 중심의 통제된 야간 실행이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페일오버/페일백 실무 운영 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 네트워크 일시 지연(1초)으로 인해 1분 동안 마스터 권한이 좌우로 10회 이상 바뀌며 **클러스터가 핑퐁 진동(Flapping)하여 시스템 전면 마비** | **연속 3회 헬스체크 실패(최소 5초) 확인 시에만 전환하는 히스테리시스 유예 타이머 및 실패 노드 격리 룰 적용** | 일시적 네트워크 플리커에 의한 플래핑 100% 차단 |
| 수리된 구 마스터가 재기동되면서 자동으로 마스터 권한을 회수(Auto-Failback)하여 **대기 노드에 저장된 최신 1시간 치 결제 데이터가 영구 삭제되는 참사 발생** | **페일백은 자동화를 절대 금지하고, LSN 차분 동기화 검증 후 관리자가 수동 승인하는 수동 페일백 정책 강제** | 페일백 시 데이터 덮어쓰기 및 데이터 역전 원천 방지 |
| 페일오버 시 클라이언트 애플리케이션의 DB Connection Pool이 구 마스터 IP를 계속 물고 있어 **마스터가 승격되었음에도 대고객 서비스 오류가 지속되는 결함** | **HikariCP 등 커넥션 풀에 연결 유효성 검사(`testOnBorrow`) 및 자동 재연결(Keepalive) 파라미터를 필수 튜닝** | 페일오버 즉시 클라이언트 세션 자동 정상화 보장 |

#### 한줄 요약
- 히스테리시스 타이머로 플래핑을 막고, 수동 페일백으로 데이터 역전을 방어하며, 커넥션 풀 튜닝으로 즉각 정상화를 달성한다.

## Ⅶ. 결론

- 고가용성 인프라의 장애 복구와 시스템 복원력을 완성하는 핵심 양방향 라이프사이클인 **자동 페일오버 및 페일백 체계**는 비상시의 신속성과 평시 복귀의 안전성을 완벽히 조화시키는 고도의 엔지니어링 규범이며, 실무 구현 시 **다계층 헬스체크 및 히스테리시스 타이머 기반 플래핑 방지**, **STONITH 펜싱 기반 무인 자동 페일오버 확립**, **LSN 기반 차분 역복제(`pg_rewind`)를 통한 데이터 정합성 사수**, **관리자 승인 기반의 야간 통제 페일백 정책 집행**을 완성하여 최고 수준의 가용성과 완벽한 데이터 무결성을 완성

#### 한줄 요약
- 자동 페일오버의 신속성과 통제된 페일백의 안전성을 통해 무결점 고가용성 라이프사이클을 완성한다.
