## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **페일오버**: 주 자원 장애 때 대기 자원이 역할•쓰기 권한•요청 경로를 승계하는 처리이다.
- **페일백**: 복구된 원래 자원이나 정상 구조로 서비스 역할을 다시 이전하는 처리이다.
- **자동 전환**: 장애 탐지•승계•접속 경로 변경과 안정화 후 복귀를 정책에 따라 수행하는 자동화 기법이다.

</details>

- 정의/개념: 장애 시 승계하고 안정화 뒤 복귀하는 **자동 페일오버•페일백**이다.
- 배경/필요성: 수동 승계는 RTO를 늘리고 검증 없는 복귀는 **데이터 역전**을 유발한다.

#### 한줄 요약

- 장애 시 예비 서버 승계와 데이터 정합성 확인 후 정상 구조 복귀가 핵심이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **상태 확인**: 응답•업무 기능•하위 의존성을 검사하여 노드의 서비스 가능 여부를 판단하는 절차이다.
- **복구 목표 시간(Recovery Time Objective, RTO)**: 서비스 중단 후 업무를 재개해야 하는 최대 허용 시간이다.
- **전환 유예 타이머**: 복구 직후 바로 재전환하지 않고 안정 상태를 확인하도록 강제하는 대기 시간이다.
- **플래핑 방지**: 유예•승인•롤백 조건으로 짧은 장애와 복구에 따른 반복 역할 전환을 억제하는 통제이다.

</details>

- 다중 상태판정•펜싱의 **안전한 승계**가 핵심이다.
- 역복제•정합성 검증의 **통제된 복귀**가 핵심이다.
- 유예•승인•롤백의 **플래핑 방지**가 핵심이다.

#### 한줄 요약

- 오진 시 이중 쓰기를 막는 기존 주 서버의 선행 쓰기 차단이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **활성 노드**: 현재 요청 처리와 쓰기 권한을 담당하는 노드이다.
- **대기 노드**: 활성 노드의 상태를 복제받고 장애 승계를 준비하는 노드이다.
- **가상 IP 주소(Virtual IP Address, VIP)**: 활성 노드가 바뀌어도 클라이언트가 같은 서비스 주소로 접속하게 하는 논리 주소이다.
- **로드밸런서(Load Balancer, LB)**: 요청을 정상 노드에 분산하는 접속 경로 장치이다.
- **도메인 이름 시스템(Domain Name System, DNS)**: 서비스 이름을 새 정상 노드의 주소로 연결하는 체계이다.

</details>

```text
자동 전환 체계
├─ 상태확인•쿼럼
├─ 펜싱•역할 전환
├─ VIP•LB•DNS 진입점
├─ 순방향•역방향 복제
└─ 유예•승인•복귀 정책
```

선의 의미: 장애 판정과 쓰기 차단부터 경로 전환•복제와 복귀 정책까지의 정적 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 상태확인•쿼럼 | 기능•의존성•**지속시간 판정** |
| 펜싱•역할 전환 | 이전 쓰기 차단•**대기 승격** |
| VIP•LB•DNS 진입점 | 사용자 **접속 경로 전환** |
| 순방향•역방향 복제 | 승계 전후 **데이터 동기화** |
| 유예•승인•복귀 정책 | 안정성•점진 원복•**롤백** |

#### 한줄 요약

- 장애 판정•기존 주체 차단•대기 승격•접속 경로 전환의 연계가 핵심이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **펜싱**: 이전 활성 노드가 공유 데이터에 쓰지 못하도록 전원•스토리지•쓰기 권한을 차단하는 조치이다.
- **역복제**: 페일오버 후 새 활성 노드의 변경분을 복구된 원 노드로 반대 방향 복제하는 처리이다.
- **점진 페일백**: 복구 노드의 데이터•용량•안정성을 확인하며 트래픽과 역할을 단계적으로 되돌리는 절차이다.

</details>

```text
       상태 감시기
              │ 1. 장애•쿼럼•지속시간 판정
              ▼
       전환 제어기
              ├─ 2. 기존 쓰기 펜싱
              └─ 3. 대기 승격•진입점 전환
                          │
                          ▼
       대기 노드
              │ 4. 역복제•안정성 검증
              ▼
       페일백 승인자
              │ 5. 승인•점진 페일백
              ▼
                전환 절차 완료
```

**동작 원리**

1. **장애•쿼럼•지속시간 판정**: 오진•플래핑 조건을 확인한다.
2. **기존 쓰기 펜싱**: 이전 활성 접근을 차단한다.
3. **대기 승격•진입점 전환**: 최신 복제본•접속점을 변경한다.
4. **역복제•안정성 검증**: 변경분•용량•정합성을 확인한다.
5. **승인•점진 페일백**: 유예•롤백 조건을 적용한다.

#### 한줄 요약

- 기존 쓰기 차단과 접속 경로 전환 후 역복제를 확인하는 전환 절차이다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **자동 페일오버**: 상태 확인과 정책에 따라 사람의 승인 없이 대기 노드를 활성화하는 방식이다.
- **수동 페일백**: 데이터 동기화와 안정 상태를 운영자가 검증한 뒤 원래 구조로 복귀하는 방식이다.
- **전환 주기**: 장애를 판정해 대기 자원으로 승계한 뒤 데이터 정합성과 안정성을 확인하고 정상 구조로 복귀하는 전체 과정이다.

</details>

페일오버와 페일백은 선택 가능한 대안이 아니라 장애 승계와 정상 복귀로 이어지는 앞뒤 단계이며, 전체 과정을 **전환 주기** 라고 한다.

| 전환 단계 | 시작 조건 | 목적•핵심 통제 | 주요 위험 |
|:---|:---|:---|:---|
| 페일오버 | 주 자원의 **장애 확정** | 기존 쓰기 펜싱•쿼럼 확인 후 대기 자원으로 서비스 승계 | 오진•이중 쓰기•세션 손실 |
| 페일백 | **역복제•안정성 검증** 완료 | 데이터 정합성•용량•유예 조건 확인 후 정상 구조로 역할 복귀 | 데이터 역전•플래핑•재중단 |

중단 시간을 줄여야 하는 승계에는 **자동 페일오버**, 데이터 역전 위험이 있는 복귀에는 검증과 승인을 거치는 **수동 페일백**이 주로 사용된다.

#### 한줄 요약

- 신속한 페일오버와 데이터 정합성을 우선한 신중한 페일백이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **플래핑**: 짧은 장애와 복구가 반복되어 역할 전환이 빈번하게 일어나는 현상이다.
- **스플릿 브레인**: 네트워크 분리 뒤 여러 노드가 동시에 활성 주체가 되어 쓰기가 충돌하는 상태이다.
- **데이터 역전**: 최신 변경분이 없는 복구 노드를 성급히 활성화하여 새 데이터가 사라지는 문제이다.
- **데이터베이스(Database, DB) 쓰기 차단**: 장애로 의심되는 기존 노드의 저장 권한을 먼저 끊어 승격 노드와의 이중 쓰기를 막는 조치이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 상태 신호로 생기는 **오진•RTO 지연** | **다중 상태판정•전환 훈련** | 승계의 **정확도•속도** 향상 |
| **이중 쓰기•데이터 역전** | **펜싱•역복제 적용** | **데이터 정합성** 확보 |
| **조기 복귀•플래핑** | **유예•승인•점진 전환** | **재중단 위험** 감소 |

#### 한줄 요약

- 기존 DB 쓰기 차단 후 대기 DB 승격을 통한 이중 쓰기를 방지한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **전환 전제조건**: 대상 노드의 데이터 최신성•대체 용량•의존성 상태가 모두 충족되어야 한다는 조건이다.
- **전환 결정**: 장애 판정과 펜싱이 완료되면 페일오버하고 역복제와 안정화가 끝난 뒤 페일백하는 판단이다.

</details>

- 장애 판정•펜싱 완료 시 **페일오버**, 역복제•안정화 후 **페일백**이 핵심이다.

#### 한줄 요약

- 이중 쓰기 방지와 데이터 정합성을 포함한 안전한 자동 전환 주기가 핵심이다.
