## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **자동 페일오버(Auto Failover)**: 주 노드 장애를 감지해 대기 노드를 자동 승격하는 장애 복구 절차.
- **페일백(Failback)**: 복구 노드를 재동기화한 뒤 주 역할을 돌려주는 원상 복구 절차.
- **복구 시간 목표(Recovery Time Objective, RTO)**: 장애 후 서비스 복구까지 허용하는 최대 시간.

</details>

- 정의/개념: 장애 노드를 격리하고 대기 노드를 승격한 뒤 복구 노드를 재편입하는 **고가용성 전환 체계**
- 배경/필요성: 수동 전환은 사람이 장애를 인지하고 판단하는 시간만큼 **RTO**를 늘리고 성급한 복귀는 미동기 데이터를 잃게 하므로, 감지·격리·승격과 재동기화 확인을 규칙으로 고정한 전환 계층을 운영자 판단 자리에 대신 놓아 개입 시간을 제거할 필요

#### 한줄 요약
- 장애 시 대기 노드로 자동 전환하고, 복구 후 데이터 정합성을 확인해 원래 구성으로 돌아간다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **히스테리시스(Hysteresis)**: 연속 실패와 복구 안정 시간을 요구해 잦은 역할 전환을 억제하는 제어 방식.
- **플래핑(Flapping)**: 일시적 상태 변화로 노드 역할이 반복 전환되는 현상.
- **로그 시퀀스 번호(Log Sequence Number, LSN)**: 로그 순서를 식별해 노드 간 적용 위치를 비교하는 번호.

</details>

- 장애 전환은 자동화하고 원상 복귀는 승인하는 **비대칭 운영 정책**
- 연속 실패·복구 안정 시간으로 역할 **플래핑** 억제
- 복구 노드의 대기 모드 편입과 **LSN** 동기화로 데이터 역전 방지

#### 한줄 요약
- 장애 전환은 빠르게 자동화하되 원상 복귀는 최신 데이터 확인 후 통제한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **쿼럼(Quorum)**: 과반 동의로 유효한 클러스터 파티션을 정하는 합의 기준.
- **STONITH(Shoot The Other Node In The Head)**: 장애 노드의 전원이나 저장소 접근을 차단하는 펜싱 방식.
- **가상 IP(Virtual IP, VIP)**: 활성 노드가 인계받아 서비스 접점을 유지하는 논리 주소.

</details>

```text
[고가용성 클러스터]
|
+-- [클러스터 제어기]
|   +-- [헬스체크·쿼럼]
|   `-- [펜싱 장치]
|
+-- [서비스 접점]
|   `-- [VIP]
|
`-- [데이터 계층]
    +-- [주 노드]
    `-- [대기 노드]
```

선의 의미: 가지는 클러스터 내부의 포함·소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 클러스터 제어기 | **헬스체크·쿼럼** 기반 역할 전환 결정 |
| 펜싱 장치 | 구 주 노드의 전원·저장소 접근 **차단** |
| VIP | 활성 노드로 서비스 **접점 인계** |
| 주·대기 노드 | 트랜잭션 처리와 **복제 상태** 보유 |

#### 한줄 요약
- 제어기가 두 노드의 역할을 정하고, 펜싱·VIP·복제 계층이 안전한 전환을 지원한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연결 드레이닝(Connection Draining)**: 기존 요청을 완료한 뒤 신규 연결만 다른 노드로 보내는 전환 방식.

</details>

```text
장애 노드        클러스터 제어기        대기·복구 노드
    |                    |                    |
    |------------------->| 장애 신호          |
    |                    | 1. 장애 판정       |
    |<-------------------| 2. 노드 펜싱       |
    |                    |------------------->|
    |                    | 3. 대기 노드 승격  |
    |                    |<-------------------|
    |                    | 4. 복구 노드 동기화|
    |                    |------------------->|
    |                    | 5. 역할 원상 복귀  |
    |<----------------------------------------| 서비스 재개
```

**동작 원리**

1. **장애 판정**: 연속 헬스체크 실패와 쿼럼으로 장애 확정
2. **노드 펜싱**: 구 주 노드의 쓰기 권한 차단
3. **대기 노드 승격**: 대기 노드 승격과 VIP 인계
4. **복구 노드 동기화**: LSN 차이를 재생해 최신 상태 일치
5. **역할 원상 복귀**: 연결 드레이닝 후 승인 기반 역할 전환

#### 한줄 요약
- 장애를 확정해 대기 노드로 전환하고, 복구 노드를 최신화한 뒤 승인받아 역할을 되돌린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **복구 시점 목표(Recovery Point Objective, RPO)**: 장애 시 허용하는 최대 데이터 손실 시점.

</details>

| 전환 절차 | 자동 페일오버 | 통제 페일백 |
|:---|:---|:---|
| 적용 기준 | 주 노드 장애 확정 시 | 복구 노드 동기화 완료 시 |
| 핵심 특징 | **RTO** 단축을 위한 자동 승격 | **RPO** 보존을 위한 승인 전환 |
| 한계 | 오탐 시 **플래핑** 위험 | 역동기화 누락 시 **데이터 역전** 위험 |

#### 한줄 요약
- 장애 전환은 복구 속도가, 원상 복귀는 데이터 정합성이 우선이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **연결 유효성 검사(Connection Validation)**: 풀에서 꺼낸 연결의 활성 노드 도달 여부를 확인하는 검사.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 일시 지연을 장애로 오판해 **플래핑** 발생 | 연속 실패·복구 안정 시간 기반 **히스테리시스** 적용 | 불필요한 역할 전환 억제 |
| 구 주 노드 재기동으로 **데이터 역전** 발생 | 대기 모드 편입 후 **LSN** 일치 검증 | 최신 트랜잭션 보존 |
| 연결 풀이 구 주 노드를 계속 참조 | **연결 유효성 검사**와 재연결 설정 | 활성 노드로 세션 전환 |

#### 한줄 요약
- 전환 오탐, 데이터 역전, 오래된 연결을 각각 유예 시간, 동기화, 재연결로 통제한다.

## Ⅶ. 결론

- 연속 장애·쿼럼 확정 시 **자동 페일오버**, LSN 일치 후 승인 기반 **페일백** 실행

#### 한줄 요약
- 장애 전환은 자동화하되 원상 복귀는 최신 데이터와 연결 상태를 확인한 뒤 실행한다.
