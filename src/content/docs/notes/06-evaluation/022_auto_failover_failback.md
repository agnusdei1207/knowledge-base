## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **자동 장애 조치(Auto Failover)**: 주 시스템 장애 발생 시 모니터링 시스템이 이를 자동 감지하고 대기 시스템으로 서비스 트래픽과 역할을 무중단 우회 승계하는 기술.
- **원상 복구(Failback)**: 장애가 발생했던 주 시스템이 정상화된 후 최신 데이터를 동기화하고 주 역할을 안전하게 다시 회수하는 절차.
- **장애 조치 자동화(Failover Automation)**: 운영자의 수동 개입 없이 헬스체크, 리더 선출, 라우팅 변경, 펜싱을 자동 실행하여 RTO를 최소화하는 체계.

</details>

- 정의/개념: 장애 승계 **페일오버**와 정상 복귀 **페일백** 자동화
- 배경/필요성: 수동 전환 지연과 무검증 복귀로 **RTO·데이터 손실 증가**

#### 한줄 요약

- 장애 시 자동 승계, 검증 후 **안전한 정상 복귀**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **헬스체크(Health Check)**: L4/L7 계층 및 DB 프로세스 수준에서 주기적으로 서비스 정상 동작 여부를 확인하는 모니터링 메커니즘.
- **가상 IP(VIP, Virtual IP)**: 마스터와 스탠바이 서버 간에 동적으로 이동하며 클라이언트 연결의 영속성을 보장하는 유동 IP 주소.
- **데이터 정합성 검증(Data Consistency Validation)**: Failover 또는 Failback 전후 복제 지연 및 트랜잭션 무결성을 검증하여 데이터 유실을 방지하는 절차.
- **플래핑 방지(Flapping Prevention)**: 네트워크 불안정으로 인해 마스터 권한이 반복적으로 전환되는 진동 현상을 지연 타이머와 댐핑 기법으로 억제하는 제어 기술.

</details>

- **상태 확인·펜싱** 후 안전한 대기 노드 승격
- 역복제와 데이터 정합성 검증 후 정상 노드 복귀
- **RTO** 내 승계와 유예 타이머 기반 **플래핑 방지**

#### 한줄 요약

- 장애 확정과 **기존 쓰기 차단 후 승격**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모니터링 에이전트(Monitoring Agent)**: 노드 내부 및 외부에서 프로세스 상태, 리소스 임계치, 헬스체크 핑을 지속 감시하는 컴포넌트.
- **오케스트레이터(Orchestrator)**: 장애 판정, 과반 합의, 승격 명령, 펜싱 트리거를 총괄 제어하는 클러스터 매니저(예: Keepalived, Pacemaker, Patroni).
- **라우팅 전환 계층(Routing Switch)**: DNS TTL 변경, BGP Anycast 라우팅 갱신, 글로벌 로드밸런서(GSLB) 전환을 통해 트래픽 방향을 변경하는 인프라.

</details>

```text
자동 전환 오토 롤백 파이프라인 무결 쉴드 락 방어 체계
├─ 상태확인 헬스체크 핑•과반 쿼럼 심판 타결
├─ 무자비 샷건 펜싱 킬 커트•1인 독재 역할 롤백 턴 전환
├─ VIP 우회 낚아채 스위칭•LB 분산 렌더링•DNS 프론트 진입점 관문 스위치 턴 라우팅
├─ 0.1초 무결 순방향 복제 락•땜질 복구 역방향 재동기화 복제 채움
└─ 롤백 대기 락 유예•사살 무결 점검 승인•정상 회귀 원복 턴 복귀 정책 룰
```

선의 의미: 감지·전환·라우팅·복제·복귀의 정적 관계

| 구성요소 | 책임 |
|:---|:---|
| 상태 확인·쿼럼 | 앱 기능과 장애 지속시간 판정 |
| 펜싱·역할 전환 | **활성 노드** 차단과 **대기 노드** 승격 |
| VIP·LB·DNS | 외부 **진입점 라우팅 전환** |
| 순방향·역방향 복제 | 전환 전후 데이터 정합성 유지 |
| 유예·승인·복귀 정책 | 플래핑 억제와 **점진 페일백** 통제 |

#### 한줄 요약

- 감지·펜싱·승격·라우팅을 잇는 **자동 전환 체계**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장애 인지 및 판정(Fault Detection & Quorum)**: 헬스체크 실패 임계치 도달 및 쿼럼 확인을 통해 Failover 실행을 확정하는 단계.
- **승격 및 승계(Promotion & Failover)**: 스탠바이 노드를 마스터로 승격하고 VIP 및 라우팅 경로를 갱신하여 클라이언트 요청을 수용하는 단계.
- **동기화 및 복귀(Sync & Failback)**: 기존 마스터를 복구한 뒤 변경된 트랜잭션 델타를 역동기화하고 안전하게 본래 상태로 롤백 전환하는 단계.

</details>

```text
       상태 감시기
              │ 1. 장애•쿼럼•지속시간 판정
              ▼
       전환 제어기
              ├─ 2. 기존 쓰기 펜싱
              └─ 3. 대기 승격•진입점 전환
                          │
                          ▼
       대기 노드
              │ 4. 역복제•안정성 검증
              ▼
       페일백 롤백 턴 승인자
              │ 5. 승인•점진 페일백
              ▼
                자동 전환 절차 완료
```

### 동작 원리

1. **장애•쿼럼•지속시간 판정**: 지연과 실제 장애 구분
2. **기존 쓰기 펜싱**: 이전 리더의 **저장 접근 차단**
3. **대기 승격•진입점 전환**: 대기 노드와 라우팅 활성화
4. **역복제•안정성 검증**: 데이터·용량·기능 검증
5. **승인•점진 페일백**: 승인 후 트래픽 단계적 복귀

#### 한줄 요약

- 펜싱 후 승계하고 역복제 검증 후 **점진 복귀**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **자동 장애 조치(Automatic Failover)**: 사전 정의된 정책에 따라 시스템이 스스로 감지 및 전환하여 RTO를 초~분 단위로 최소화하는 방식.
- **수동 장애 조치(Manual Failover)**: 관리자가 BIA 및 정합성 영향을 검토한 뒤 승인 버튼을 통해 전환을 통제하여 오작동 위험을 방지하는 방식.

</details>

페일오버와 페일백은 **전환 주기**의 순차 단계

| 구분 | 발동 조건 | 운영 방식 | 한계 |
|:---|:---|:---|:---|
| 페일오버 | 주 노드 장애 확정 | **자동 페일오버** | 오판·이중 쓰기·세션 단절 |
| 페일백 | 역복제·안정성 검증 완료 | **수동 페일백** | 데이터 역전·플래핑·재중단 |

RTO 단축에는 **자동 페일오버**, 복귀 안전에는 **수동 페일백** 적용

#### 한줄 요약

- 신속한 자동 승계와 **검증된 수동 복귀 조합**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스플릿 브레인 방지(Split-Brain Prevention)**: Failover 시 구 마스터에 대한 STONITH 강제 펜싱을 선행하여 복수 마스터 쓰기 충돌을 원천 차단.
- **데이터 역류 차단(Reverse Replication Block)**: Failback 시 데이터 덮어쓰기로 인한 데이터 소실을 방지하기 위해 LSN(Log Sequence Number) 비교 후 차분 동기화 수행.
- **사전 리허설(DR Drill)**: 정기 모의 훈련을 통해 Failover 및 Failback 스크립트의 동작과 소요 시간을 실측하고 검증하는 활동.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거짓 장애 판정 | 다중 헬스체크·전환 훈련 | 승계 정확도 향상 |
| 스플릿 브레인·데이터 역전 | 쓰기 펜싱·**역복제** 검증 | 데이터 정합성 확보 |
| 조기 복귀·**플래핑** | 유예 타이머·점진 페일백 | 재중단 위험 감소 |

#### 한줄 요약

- 기존 쓰기를 **펜싱한 뒤 대기 노드 승격**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지능형 장애 복구 거버넌스(Automated Recovery Governance)**: 고속 자동 Failover와 신중한 데이터 검증 기반 Failback을 조화시켜 가용성과 데이터 무결성을 동시에 보장하는 체계.

</details>

- 장애·펜싱 확인 시 자동 승계, 역복제 검증 후 **수동 복귀**

#### 한줄 요약

- 신속성은 자동 승계, 정합성은 **검증된 점진 복귀**
