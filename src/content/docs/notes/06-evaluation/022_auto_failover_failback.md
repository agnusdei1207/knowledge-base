## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **자동 장애 조치(Auto Failover)**: 주 시스템 장애 시 대기 시스템으로 서비스 트래픽과 역할을 자동 우회 승계하는 기술.
- **원상 복구(Failback)**: 장애 주 시스템이 정상화된 후 최신 데이터를 동기화하고 주 역할을 안전하게 회수하는 절차.

</details>

- 정의/개념: 주 시스템 장애 시 대기 노드로 자동 전환(Failover)하고 복구 후 주 노드로 안전하게 환원(Failback)하는 고가용성 제어 체계
- 배경/필요성: 수동 전환 지연과 무검증 복귀로 인한 **RTO 지연 및 데이터 역전 손실 방지**

#### 한줄 요약

- 장애 시 자동 승계, 검증 후 **안전한 정상 복귀**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **헬스체크(Health Check)**: 계층별로 서비스 정상 동작 여부를 주기적으로 확인하는 모니터링 기법.
- **가상 IP(VIP, Virtual IP)**: 마스터와 스탠바이 간에 동적으로 이동하며 연결성을 보장하는 유동 IP.
- **플래핑 방지(Flapping Prevention)**: 마스터 권한이 반복적으로 전환되는 진동 현상을 유예 타이머로 억제하는 기술.

</details>

- **상태 확인·펜싱** 후 안전한 대기 노드 승격
- 역복제와 데이터 정합성 검증 후 정상 노드 복귀
- **RTO** 내 승계와 유예 타이머 기반 **플래핑 방지**

#### 한줄 요약

- 장애 확정과 **기존 쓰기 차단 후 승격**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모니터링 에이전트(Monitoring Agent)**: 프로세스 상태와 헬스체크 핑을 지속 감시하는 컴포넌트.
- **오케스트레이터(Orchestrator)**: 장애 판정, 과반 합의, 승격 명령, 펜싱을 총괄 제어하는 클러스터 매니저.
- **라우팅 전환 계층(Routing Switch)**: VIP, DNS, 로드밸런서를 통해 트래픽 방향을 변경하는 인프라.

</details>

```text
자동 페일오버·페일백 아키텍처
├─ 상태 감시부: L4/L7 헬스체크 / 쿼럼 과반수 합의
├─ 장애 격리부: 구 마스터 펜싱(STONITH) / 스토리지 쓰기 차단
├─ 진입 전환부: VIP 스위칭 / LB·DNS 라우팅 우회
├─ 복제 제어부: 순방향 복제 / 역방향 차분 동기화
└─ 복귀 통제부: 유예 타이머 / 데이터 정합성 검증 / 수동 점진 복귀
```

선의 의미: 상태 감시부터 격리, 라우팅 전환, 데이터 복제 및 안전한 복귀 통제로 이어지는 자동 전환 체계.

| 구성요소 | 책임 |
|:---|:---|
| 상태 확인·쿼럼 | 앱 기능과 장애 지속시간 판정 |
| 펜싱·역할 전환 | **활성 노드** 차단과 **대기 노드** 승격 |
| VIP·LB·DNS | 외부 **진입점 라우팅 전환** |
| 순방향·역방향 복제 | 전환 전후 데이터 정합성 유지 |
| 유예·승인·복귀 정책 | 플래핑 억제와 **점진 페일백** 통제 |

#### 한줄 요약

- 감지·펜싱·승격·라우팅을 잇는 **자동 전환 체계**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장애 인지 및 판정(Fault Detection & Quorum)**: 헬스체크 실패 임계치 도달 및 쿼럼 확인으로 Failover를 확정하는 단계.
- **동기화 및 복귀(Sync & Failback)**: 기존 마스터 복구 후 변경 델타를 역동기화하고 본래 상태로 롤백하는 단계.

</details>

```text
       상태 감시기
              │ 1. 장애•쿼럼•지속시간 판정
              ▼
       전환 제어기
              ├─ 2. 기존 쓰기 펜싱
              └─ 3. 대기 승격•진입점 전환
                          │
                          ▼
       대기 노드
              │ 4. 역복제•안정성 검증
              ▼
       페일백 승인자
              │ 5. 승인•점진 페일백
              ▼
        자동 전환 절차 완료
```

**동작 원리**

1. **장애·쿼럼·지속시간 판정**: 일시적 지연과 실제 장애 상태 구분
2. **기존 쓰기 펜싱**: 이전 리더의 스토리지 저장 접근 강제 차단
3. **대기 승격·진입점 전환**: 대기 노드 승격 및 라우팅 경로 활성화
4. **역복제·안정성 검증**: 데이터 정합성, 용량, 애플리케이션 기능 검증
5. **승인·점진 페일백**: 관리자 승인 후 트래픽의 단계적 정상 복귀

#### 한줄 요약

- 펜싱 후 승계하고 역복제 검증 후 **점진 복귀**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **자동 장애 조치(Auto Failover)**: 정책에 따라 시스템이 스스로 감지 및 전환하여 RTO를 단축하는 방식.
- **수동 원상 복구(Manual Failback)**: 데이터 정합성 및 안정성을 확인한 후 관리자 통제 하에 복귀하는 방식.

</details>

| 전환 단계 | 자동 페일오버 (Auto Failover) | 수동·점진 페일백 (Manual Failback) |
|:---|:---|:---|
| 적용 기준 | 주 노드 장애 확정 시 즉각 실행 | 주 노드 수리 및 역복제 동기화 완료 시 |
| 핵심 특징 | 헬스체크 및 쿼럼 기반 자동 승격 (RTO 단축) | 데이터 정합성 및 LSN 검증 후 통제 하에 전환 |
| 한계 | 일시적 지연에 대한 오판 및 플래핑 위험 | 관리자 개입 필요 및 전환 지연시간 소요 |

> 요약: RTO 단축에는 자동 페일오버를, 복귀 안전성 확보에는 수동 점진 페일백을 조합 적용.

#### 한줄 요약

- 신속한 자동 승계와 **검증된 수동 복귀 조합**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스플릿 브레인 방지(Split-Brain Prevention)**: Failover 시 구 마스터에 대한 STONITH 강제 펜싱을 선행하여 복수 마스터 쓰기 충돌을 원천 차단.
- **데이터 역류 차단(Reverse Replication Block)**: Failback 시 데이터 덮어쓰기로 인한 데이터 소실을 방지하기 위해 LSN(Log Sequence Number) 비교 후 차분 동기화 수행.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거짓 장애 판정 | 다중 헬스체크·전환 훈련 | 승계 정확도 향상 |
| 스플릿 브레인·데이터 역전 | 쓰기 펜싱·**역복제** 검증 | 데이터 정합성 확보 |
| 조기 복귀·**플래핑** | 유예 타이머·점진 페일백 | 재중단 위험 감소 |

#### 한줄 요약

- 기존 쓰기를 **펜싱한 뒤 대기 노드 승격**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **지능형 장애 복구 거버넌스(Automated Recovery Governance)**: 고속 자동 Failover와 신중한 데이터 검증 기반 Failback을 조화시키는 체계.

</details>

- 신속한 자동 페일오버와 역복제 검증 기반 **통제된 점진 페일백 체계 구축**

#### 한줄 요약

- 신속성은 자동 승계, 정합성은 **검증된 점진 복귀**
