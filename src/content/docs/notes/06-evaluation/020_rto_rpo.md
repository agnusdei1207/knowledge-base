## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **목표 복구 시간(Recovery Time Objective, RTO)**: 시스템 장애 발생 시점부터 서비스가 정상적으로 재개되기까지 허용되는 최대 복구 시간.
- **목표 복구 시점(Recovery Point Objective, RPO)**: 시스템 장애 발생 시 데이터 유실이 허용되는 최대 시간적 범위(과거 복구 시점 기준).
- **업무 영향도 분석(Business Impact Analysis, BIA)**: 시스템 중단에 따른 정량적 재무 손실과 정성적 업무 영향을 평가하여 업무별 복구 우선순위와 RTO/RPO 기준을 도출하는 기법.

</details>

- 정의/개념: 복구 시간 **RTO**와 데이터 손실 시점 **RPO**
- 배경/필요성: BIA 없이 일률 목표를 정하면 **과잉·과소 투자 발생**

#### 한줄 요약

- RTO는 미래 복구, RPO는 **과거 손실 한계**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중단시간(Downtime)**: 시스템 장애 발생부터 Failover 및 데이터 복구를 거쳐 서비스가 정상 오픈될 때까지의 총 서비스 불가 시간.
- **복구 시점(Recovery Point)**: 백업 데이터 또는 스토리지 복제본을 기반으로 트랜잭션 정합성을 복원해 낸 과거의 특정 시점.
- **비용-목표 상충(Trade-off)**: RTO와 RPO를 단축(0에 수렴)할수록 액티브 인프라 및 실시간 동기 복제 비용이 기하급수적으로 증가하는 관계.

</details>

- **다운타임**으로 RTO 달성 여부 측정
- **복구 시점**으로 RPO 달성 여부 측정
- **비용·목표 상충**을 훈련 실측으로 검증

#### 한줄 요약

- 빠른 기동과 최신 복제본을 **각각 독립 검증**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **동기 복제(Synchronous Replication)**: 주 센터 디스크 쓰기와 원격지 디스크 저장을 동시에 확인하여 RPO=0을 보장하는 복제 방식.
- **비동기 복제(Asynchronous Replication)**: 주 센터 로컬 저장 완료 후 원격지로 백그라운드 전송하여 성능을 유지하되 수 초~수 분의 RPO 손실을 감수하는 방식.
- **스냅숏 및 백업(Snapshot & Backup)**: 특정 시점의 데이터 일관성을 고정한 스냅숏 이미지와 원격지 분리 보관을 위한 백업 체계.

</details>

```text
RTO•RPO 관리 체계
├─ BIA•업무 우선순위
├─ RTO•RPO 목표
├─ 복제•백업•복구 시점
├─ 선언•승계•업무 재개
└─ 훈련•실측•개선
```

선의 의미: BIA·목표·복구 수단·검증의 정적 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| BIA•업무 우선순위 | **BIA**로 업무 우선순위 도출 |
| RTO•RPO 목표 | 업무별 **RTO**•**RPO** 설정 |
| 복제•백업•복구 시점 | 동기·비동기·백업 수단 선택 |
| 선언•승계•업무 재개 | 재해 선언·승계·재개 통제 |
| 훈련•실측•개선 | 실제 시간·손실 측정·개선 |

#### 한줄 요약

- BIA에서 **목표·보호 수단·복구 절차·훈련 연결**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장애 승계(Failover)**: 주 시스템 장애 시 대기 시스템으로 트래픽과 권한을 자동 또는 수동으로 우회 전환하는 절차.
- **복구 검증(Recovery Validation)**: Failover 완료 후 시스템 성능, 트랜잭션 무결성, 목표 RTO 준수 여부를 종합 확인하는 절차.

</details>

```text
       업무 책임자
              │ 업무•의존성•중단•손실 영향
              ▼
       BIA 분석가
              │ 1. RTO·RPO·업무 우선순위 산정
              ▼
       보호 체계
              │ 2. 복제 주기·복구·승계 조건 설계
              ▼
       복구 환경
              │ 3. 재해 선언·복구·업무 재개 실행
              ▼
       검증팀
              │ 4. 실제 RTO·RPO·정합성 검증
              ▼
                실제 복구시간·데이터 손실·격차
```

### 동작 원리

1. **RTO·RPO·업무 우선순위 산정**: BIA·비용 기반 목표 설정
2. **복제 주기·복구·승계 조건 설계**: 보호·전환 수단 구성
3. **재해 선언·복구·업무 재개 실행**: 복구 절차 가동
4. **실제 RTO·RPO·정합성 검증**: 시간·손실·기능 측정

#### 한줄 요약

- 복구 훈련으로 **실제 RTO·RPO·업무 정합성 측정**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RTO 적용 기준**: 서비스 중단 허용 시간 한도로서 서버 부팅, 네트워크 전환, 애플리케이션 기동 시간에 좌우됨.
- **RPO 적용 기준**: 데이터 유실 허용 시점 한도로서 스토리지 복제 주기, 로그 동기화 방식에 좌우됨.

</details>

| 비교 기준 | **RTO (Recovery Time Objective)** | **RPO (Recovery Point Objective)** |
|:---|:---|:---|
| 적용 기준 | 서비스 재개 **허용 시간** | 데이터 복구 **허용 시점** |
| 통제 수단 | 승계·기동·검증 시간 단축 | 복제·백업 주기 단축 |
| 초과 원인 | 선언·기동·검증 **지연** | 복제 지연·백업 **누락** |

#### 한줄 요약

- RTO는 중단시간, RPO는 **데이터 손실 시점**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **실제 복구 소요 시간(Actual RTO)**: 장애 발생 시점부터 시스템 기동 및 검증을 거쳐 서비스가 재개되기까지 실제 측정된 시간.
- **실제 데이터 손실(Actual RPO)**: 장애 발생 시점과 마지막으로 복원된 백업/복제본 데이터 시점 사이의 실제 데이터 누락 범위.
- **ISO 22313**: 비즈니스 연속성 관리 시스템(BCMS) 구현 및 운영 지침에 관한 국제 표준.

</details>

**ISO** 글로벌 탑 무결 바이블 지침 뼈대 프레임워크를 강제 전격 투입 락 적용하여 벤더 눈가림 야매 엑셀 꼼수를 킬 분쇄 박살 내고 무자비 BIA 현미경 달러 팩트 심판 도출 결과와 RTO RPO 롤백 쉴드 방어 마지노선 타겟 컷오프 락 픽스 복구 목표의 100% 투명 팩트 무결 동기 일치 연결 락(Lock) 팩트 검토를 깐깐 살벌 통제 스퀴즈 수행 확인한다.

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| BIA 없이 정한 복구 목표 | **ISO 22301 기반 BIA** | 업무 근거 확보 |
| 보호 수단·복구 절차 분리 | **ISO 22313 적용** | RTO·RPO 정렬 |
| 실제 달성 여부 미검증 | **복구 훈련** | 시간·손실 실측 |

#### 한줄 요약

- 치명 업무는 **동기·짧은 지연 복제 선택**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **목표 차등화(Tiered SLA)**: 모든 시스템에 획일적 기준을 적용하지 않고 업무 중요도에 따라 RTO/RPO 목표를 차등 배정하는 최적화 전략.

</details>

- 중단비용이 크면 RTO, 손실비용이 크면 **RPO 우선 단축**

#### 한줄 요약

- BIA·훈련·예산으로 **RTO·RPO 차등 결정**
