## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **용량 산정 및 계획(Capacity Planning)**: 현재 및 미래의 비즈니스 트래픽을 안정적으로 처리하기 위해 필요한 컴퓨팅, 네트워크, 스토리지 자원의 규모를 과학적으로 예측하고 증설 계획을 수립하는 활동.
- **시스템 사이징(System Sizing)**: CPU 코어 수, 메모리 용량, 디스크 IOPS, 대역폭 요구량을 수학적/공학적 모델로 계산하는 기법.
- **자원 증설 예측(Resource Forecasting)**: 데이터 증가율과 사용자 증가 추세를 분석하여 자원 고갈 시점을 사전에 파악하는 활동.

</details>

- 정의/개념: 수요·SLO로 용량과 확장 시점을 정하는 **용량 계획**
- 배경/필요성: 평균 부하로는 **피크·N-1 장애 용량 판단 불가**

#### 한줄 요약
- 피크·헤드룸·조달 시간을 반영한 **선제 확장**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워크로드 프로파일링(Workload Profiling)**: 피크 시간대 TPS, 평균 응답시간, 배치 작업 시간, 리소스 사용률 패턴 분석.
- **성능 모델링(Performance Modeling)**: 대기행렬 이론(Queueing Theory), 리틀의 법칙(Little's Law), 벤치마크 데이터를 활용한 정량 계산.
- **헤드룸 확보(Headroom & Safety Buffer)**: 스파이크 트래픽 흡수를 위해 적정 안전 마진(통상 20~30% 여유)을 반영한 사이징.
- **클라우드 오토스케일링 연계(Elastic Sizing)**: 정적 최대 용량 산정 방식에서 벗어나 기준 베이스라인과 동적 확장 임계치를 결합 설계.

</details>

- 기준선에 성장·계절·이벤트 **피크 부하** 반영
- 장애·예측 오차를 흡수할 **헤드룸** 확보
- 성장·비용·장애 가정의 **민감도 분석**

#### 한줄 요약
- 피크와 N-1에서 **SLO를 지킬 헤드룸** 산정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **컴퓨팅 및 메모리 자원(CPU & RAM Metrics)**: 동시 사용자 수, 초당 트랜잭션 수(TPS), JVM 힙 메모리 요구량.
- **스토리지 자원(Storage Metrics)**: 연간 트랜잭션 데이터 증가량, 인덱스 크기, 로그 보관 기간, 백업 용량.
- **네트워크 자원(Network Metrics)**: 페이지당 평균 크기, 동시 다운로드 처리량, 백본 스위치 대역폭 요구량.

</details>

```text
용량 계획 체계
├─ 수요•SLO
├─ 자원 모델
├─ 리드타임•헤드룸
├─ 확장 대안•비용
└─ 용량 로드맵•실측
```

선의 의미: 수요·자원·헤드룸·리드타임을 확장 로드맵으로 연결

| 구성요소 | 책임 및 계산 초점 |
|:---|:---|
| 수요•SLO | 성장·계절·이벤트 부하와 SLO 정의 |
| 자원 모델 | CPU·DB·I/O의 **병목 한계** 모델링 |
| 리드타임•헤드룸 | 예측 오차·장애 여유와 조달 시간 |
| 확장 대안•비용 | 스케일업·아웃·자동 확장 비교 |
| 용량 로드맵•실측 | 확장 일정과 부하 실측·모델 보정 |

#### 한줄 요약
- 수요·자원·**헤드룸**•**리드타임** 기반 확장 로드맵

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **현재 사용량 프로파일링(Baseline Profiling)**: APM 및 모니터링 툴을 통해 현행 시스템의 CPU, 메모리, IOPS, TPS 베이스라인을 측정하는 단계.
- **비즈니스 부하 예측(Business Load Forecasting)**: 신규 서비스 런칭, 이벤트, 마케팅 계획을 반영하여 미래 피크 TPS와 데이터 증가량을 산출하는 단계.
- **필요 자원 산정 및 사이징 모델 적용(Capacity Sizing)**: 수식 기반(예: TPC-C 벤치마크 환산법) 또는 큐잉 모델을 적용하여 필요 하드웨어 스펙을 계산하는 단계.
- **증설 및 스케일링 전략 수립(Provisioning Strategy)**: 스케일업(Scale-Up), 스케일아웃(Scale-Out) 또는 클라우드 탄력 확장을 결정하고 예산을 집행하는 단계.

</details>

```text
              [업무부서]
                  │ 성장•피크•장애 수요
                  ▼
              [계획자]
                  │ 기준선 측정 요청
                  ▼
              [대상 시스템]
                  │ 처리량•지연•포화 한계
                  ▼
              [계획자]
                  │ 1. 기준선•자원 모델 수립
                  │ 2. 미래 수요 예측
                  │ 3. 용량•확장 시점 결정
                  │   조달•확장 요청
                  ▼
              [공급자]
                  │ 조달•부하 시험 결과
                  ▼
              [계획자]
                  │ 4. 부하 검증•모델 보정
```

### 동작 원리

1. **기준선•자원 모델 수립**: 처리량·지연·포화 한계 모델링
2. **미래 수요 예측**: 성장·피크·장애 민감도 산정
3. **용량•확장 시점 결정**: 헤드룸·리드타임 역산
4. **부하 검증•모델 보정**: 피크·N-1 시험과 모델 교정

#### 한줄 요약
- 리드타임 전 확장하고 **피크·N-1 시험**으로 보정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 용량 산정(Static Provisioning)**: 피크 부하에 맞춰 최대 스펙의 물리 서버를 일괄 구매하는 온프레미스 방식.
- **동적 탄력 용량 산정(Dynamic Elastic Provisioning)**: 평균 부하에 기준을 맞추고 피크 시 클라우드 오토스케일링으로 유연하게 대응하는 비용 효율적 방식.

</details>

| 용량 산정 접근법 | 추세 분석법 (Trend Analysis) | 워크로드 모델링 (Workload Modeling) | 부하 시험 검증 (Load Testing) |
|:---|:---|:---|:---|
| 적용 기준 | 안정 성장 서비스 | 신규 기능·구조 변화 | 고위험 오픈 전 검증 |
| 핵심 특징 | 과거 추세 데이터 기반 예측 | 업무량과 자원의 인과 모델링 | 실제 한계점 및 병목 구간 검증 |
| 한계 | 급격한 워크로드 변화 대응 불가 | 복잡한 인과 관계 모델링 비용 | 대규모 시험 환경 구축 비용 수반 |

#### 한줄 요약
- 안정은 추세, 변화는 모델, 고위험은 **부하 검증**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **과다 사이징 방지(Anti-Overprovisioning)**: 과도한 안전율 적용으로 인한 예산 낭비를 막기 위해 BMT 실측 데이터 기반의 검증된 사이징 수행.
- **스파이크 부하 완충(Spike Traffic Buffering)**: 자원 증설만으로 감당하기 힘든 순간 트래픽은 Redis 캐싱 및 Kafka 대기열 큐로 완충.
- **병목 계층 사전 식별(Bottleneck Identification)**: DB 락, 커넥션 풀, 디스크 I/O 등 특정 계층의 병목으로 인한 전체 처리량 저하를 부하 테스트로 조기 파악.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순간 피크의 평균 통계 은폐 | Max TPS·지속시간 부하 시험 | 피크 용량 방어선 확보 |
| 피크 중 서버 한 대 장애 | **N-1 헤드룸** 강제 | 장애 중 처리 여유 유지 |
| 확장 방식의 비용·구조 불일치 | 업·아웃·**오토스케일링 ROI** 비교 | 적정 확장 방식 선택 |

#### 한줄 요약
- **피크·N-1·비용**으로 확장 방식과 용량 결정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **성능 안정성과 비용 효율성을 양립하는 용량 설계(Balanced Capacity Planning)**: 데이터 기반의 정밀 워크로드 분석과 탄력적 아키텍처 설계를 결합하여 서비스 안정성과 인프라 비용 최적화를 동시에 달성하는 엔지니어링 체계.

</details>

- 피크·N-1 SLO 용량을 리드타임 전에 적정 방식으로 확장

#### 한줄 요약
- **헤드룸 소진일-리드타임**에 확장 발주
