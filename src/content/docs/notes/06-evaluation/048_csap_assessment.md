## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CSAP**: 공공기관에 제공되는 클라우드 서비스의 보호조치를 평가·인증하는 제도.
- **KCMVP**: 암호모듈의 안전성과 구현 적합성을 검증하는 국내 제도.

</details>

- 정의/개념: 공공 클라우드의 관리·물리·기술 통제를 검증하는 **보안 인증 체계**
- 배경/필요성: 공공기관이 민간 클라우드 서비스를 도입할 때 민간용 일반 보안 인증만을 신뢰할 경우, 국가 정보보안 기본지침 및 공공 특화 보안 요구사항(망 분리, 국가검증 KCMVP 암호모듈 탑재, 국내 데이터센터 입지 및 로그 보존 등)을 충족하지 못해 국가 기밀 유출 및 행정 서비스 중단 위험이 초래되는 법적·보안적 결함이 발생함에 따라, 클라우드컴퓨팅법 제23조의2에 기반하여 KISA가 관리적·물리적·기술적 및 공공 특화 보호조치를 종합 평가하고 3등급제(상/중/하)로 체계화한 클라우드 보안인증(CSAP) 제도를 도입하여 **공공 데이터 중요도별 차등화된 보안 통제 확립, KCMVP 기반 데이터 암호화 및 엄격한 모의침투 시험 실증을 통한 공공 클라우드 조달 신뢰성 확보**를 달성할 필요

#### 한줄 요약
- CSAP는 공공기관용 클라우드 서비스의 보안 통제를 평가·인증한다.

## Ⅱ. 특징

- 데이터 중요도에 따른 **상·중·하 등급 체계**
- 관리·물리·기술·공공 특화의 **다영역 통제 평가**
- 서비스 유형별로 구분하는 **IaaS·SaaS·DaaS 평가**
- 공공 데이터 보호를 위한 **KCMVP 암호모듈**
- 문서 통제를 실제 공격으로 확인하는 **모의 침투 시험**
- 인증 후 변경과 통제를 확인하는 **사후 관리**

#### 한줄 요약
- 등급·유형별 평가, 공공 특화 통제, 침투 시험, 사후 관리가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── CSAP 평가 체계 ──────────────┐
│                                           │
├── [등급]                                  │
│   └── 상 · 중 · 하                        │
├── [서비스 유형]                           │
│   └── IaaS · SaaS · DaaS                  │
└── [평가 영역]                             │
    ├── 관리적 보호조치                     │
    ├── 물리적 보호조치                     │
    ├── 기술적 보호조치                     │
    └── 공공 특화 보호조치                  │
```

| 구성요소 | 책임 |
|:---|:---|
| **등급 체계** | 데이터 중요도별 보호 수준 결정 |
| **서비스 유형** | 제공 계층에 맞는 평가 범위 결정 |
| **관리적 보호조치** | 정책·인력·자산·사고 대응 평가 |
| **물리적 보호조치** | 출입·방재·장비 보호 평가 |
| **기술적 보호조치** | 격리·접근·취약점·로그 평가 |
| **공공 특화 보호조치** | 암호모듈·망·데이터 요건 평가 |

#### 한줄 요약
- 등급과 서비스 유형이 앞에서 평가 범위를 좁혀 주므로 모든 통제를 일률 적용할 때의 심사 반복 비용이 데이터 중요도에 비례한 만큼으로 줄고, 공공 특화 영역은 일반 보안 통제가 다루지 않는 KCMVP 암호모듈·망 요건을 대신 맡는다.

## Ⅳ. 흐름도

```text
[신청 사업자]
     │
     └──────── 인증 신청
                 │
                 ▼
            [평가기관]
                 │ 1. 서비스 유형·등급·범위 확정
                 │ 2. 서면·현장 통제 평가
                 │ 3. 기술 점검·침투 시험
                 ▼
            [신청 사업자]
                 │ 4. 부적합 보완·증거 제출
                 ▼
            [인증위원회]
                 │ 5. 보완 확인·인증 심의
                 └──────── 인증 결과 반환
```

**동작 원리**

1. **서비스 유형·등급·범위 확정**: 데이터 중요도와 제공 계층 분석
2. **서면·현장 통제 평가**: 정책·인력·시설·운영 증거 확인
3. **기술 점검·침투 시험**: 격리·암호·접근·취약점의 실제 동작 검증
4. **부적합 보완·증거 제출**: 원인 제거와 재시험 결과 제출
5. **보완 확인·인증 심의**: 잔여 부적합과 인증 조건 최종 판정

#### 한줄 요약
- 부적합이 곧바로 심의로 넘어가지 않고 보완·재제출 루프를 한 번 거치므로 사업자는 인증을 처음부터 다시 신청하는 대신 지적 항목만 고쳐 돌아오면 되고, 그 루프에서 원인을 제거하지 못한 항목만 인증 조건으로 남는다.

## Ⅴ. 종류 및 비교

| 비교 항목 | CSAP | FedRAMP | ISO/IEC 27017 |
|:---|:---|:---|:---|
| 적용 시장 | 대한민국 **공공 클라우드** | 미국 연방 클라우드 | 국제 클라우드 보안 |
| 평가 성격 | 공공 조달 연계 인증 | 연방 사용 승인 체계 | 정보보호 통제 지침·인증 |
| 위험 구분 | 상·중·하 등급 | 영향 수준별 기준 | 단일 통제 체계 |
| 특화 요구 | 공공 특화·KCMVP | 연방 통제·지속 감시 | CSP·고객 통제 지침 |
| 적용 판단 | 국내 공공 서비스 | 미국 연방 서비스 | 국제 보안 관리체계 |

#### 한줄 요약
- CSAP는 국내 공공, FedRAMP는 미국 연방, 27017은 국제 통제에 초점을 둔다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 중요도와 인증 등급 불일치 | 사전 **데이터 분류·등급 매핑** | **보호 수준** 적합화 |
| 공공 암호 요건의 설계 후 발견 | 초기 설계에 **KCMVP 모듈** 반영 | **재설계 비용** 방지 |
| 하부 인프라 인증 범위 오해 | 상속 통제와 **이용자 책임** 분리 확인 | **책임 공백** 해소 |
| 문서 통제와 실제 설정 불일치 | 구성 실사와 **모의 침투 시험** | **실제 보안** 검증 |
| 인증 후 중요 변경 미신고 | 변경 영향 평가와 **사후 심사** 연계 | **인증 유효성** 유지 |

#### 한줄 요약
- 등급 매핑, 암호 설계, 책임 확인, 실사, 변경 관리로 인증 위험을 줄인다.

## Ⅶ. 결론

- 대한민국 공공기관에 공급되는 민간 클라우드 서비스의 관리·물리·기술 및 공공 특화 보호조치를 엄격히 검증하여 국가 정보자산의 안전성과 조달 신뢰성을 보증하는 **공공 클라우드 보안성 및 신뢰성 인증 체계(CSAP Assessment / KISA Cloud Security Assurance Program / 3-Tier Classification & KCMVP)의 국가 법정 보안 인증 표준**으로 확고히 자리 잡았으며, SaaS 간이 인증 확대 및 상·중·하 등급별 망 분리 규제 완화와 맞물려 공공 DX 혁신을 주도하는 가운데, 실무 CSAP 인증 획득 및 공공 클라우드 도입 시에는 **취급 데이터의 보안 등급(상/중/하)과 IaaS·SaaS·DaaS 서비스 유형에 맞춘 정확한 인증 등급 매핑, 기획·설계 초기부터 국가 검증 KCMVP 암호모듈의 필수 결합, 인증 획득 후 인프라 변경 시 사후 심사와 연계하는 지속적 보안 거버넌스**를 결합하여 완벽한 공공 사이버 보안 체계를 완성

#### 한줄 요약
- 공공 데이터 위험에 맞는 등급과 실제 통제를 입증한 서비스만 도입한다.
