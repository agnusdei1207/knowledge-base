## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스플릿 브레인(Split-Brain)**: 클러스터 통신 단절 시 복수 노드가 동시 리더로 동작하여 데이터 충돌을 일으키는 현상.
- **네트워크 분할(Network Partition)**: 물리 노드는 정상이나 상호 통신망이 단절되어 상태 확인이 불가능해진 상태.
- **단일 쓰기 보장(Single-Leader Invariant)**: 분할 상황에서도 단일 리더에게만 쓰기를 허용하는 원칙.

</details>

- 정의/개념: 네트워크 분할 시 복수 리더의 동시 쓰기를 차단하기 위해 과반수 쿼럼과 펜싱으로 단일 쓰기를 보장하는 고가용성 제어 기법
- 배경/필요성: 지연과 장애의 오판으로 복수 마스터가 공존할 경우 **데이터 영구 충돌 및 불일치 발생**

#### 한줄 요약

- 분할 시 과반 진영만 쓰게 하는 **쿼럼 통제**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쿼럼(Quorum)**: 리더 선출 및 커밋 권한을 획득하기 위해 필요한 최소 과반수 투표 노드 수.
- **과반수 원칙(Majority Rule)**: 전체 노드의 과반을 획득한 그룹만 활성화하여 복수 리더를 차단하는 기법.
- **하트비트(Heartbeat)**: 노드 간 주기적 신호 교환으로 상태 및 분할 여부를 탐지하는 메커니즘.
- **펜싱(Fencing)**: 쿼럼 상실 노드의 스토리지 쓰기를 차단하기 위해 물리적·논리적으로 격리하는 기술.

</details>

- **과반수 쿼럼**으로 단일 리더 선출
- **펜싱**으로 이전 리더의 쓰기 차단
- **하트비트**·증인으로 네트워크 분할 판정

#### 한줄 요약

- 과반수 선출과 **펜싱**을 결합한 단일 쓰기 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **증인 노드(Witness Node)**: 데이터를 저장하지 않고 동률(Tie) 시 캐스팅보트 투표권만 행사하는 보조 노드.
- **임대권(Lease)**: 일정 시간 동안 특정 노드에만 쓰기 권한을 위임하는 시한부 권한 토큰.
- **세대 번호(Epoch Number)**: 리더 선출 시마다 단조 증가하여 구 리더의 쓰기 요청을 거부하는 시계열 번호.

</details>

```text
[복제 노드•투표권]---[다중 하트비트•분할 감지]---[증인•중재 노드•쿼럼]
                              │                              │
                    [임대권•임기•세대]----------[펜싱•재동기화]
```

선의 의미: 분할 감지부터 쿼럼 합의, 세대 관리 및 펜싱 격리로 이어지는 단일 쓰기 통제 구조.

| 구성요소 | 책임 |
|:---|:---|
| 복제 노드·투표권 | 리더 투표와 로그 복제 |
| 다중 하트비트·분할 감지 | 독립 경로와 타임아웃으로 장애 판정 |
| 증인·중재 노드·쿼럼 | **증인 노드**로 2노드 동률 해소 |
| 임대권·임기·세대 | **임대권·세대 번호**로 쓰기 권한 통제 |
| 펜싱·재동기화 | 이전 리더 차단과 최신 로그 복구 |

#### 한줄 요약

- 투표·증인·임대권·펜싱으로 **단일 쓰기 통제**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장애 감지(Failure Detection)**: 하트비트 누락을 감지하고 일시적 지연과 실제 분할을 구분하는 단계.
- **펜싱 실행(Fencing Execution)**: 구 리더의 전원이나 스토리지를 차단하여 쓰기를 물리적으로 차단하는 조치.

</details>

```text
       후보 노드
              │ 1. 분할 감지•새 임기 시작
              ▼
       쿼럼 관리자
              │ 2. 과반수 투표•로그 확인
              ▼
       펜싱 장치
              │ 3. 고립 노드 펜싱 실행
              ▼
       새 리더
              ├─ 4. 단일 임대권•리더 활성화
              └─ 5. 로그 재동기화•쓰기 재개
```

**동작 원리**

1. **분할 감지·새 임기 시작**: 분할 확인 및 세대 번호(Epoch) 증가
2. **과반수 투표·로그 확인**: 과반수 쿼럼 및 최신 복제 로그 검증
3. **고립 노드 펜싱 실행**: 패배 노드의 스토리지 쓰기 권한 강제 차단
4. **단일 임대권·리더 활성화**: 승자 노드에 단일 임대권 발급 및 활성화
5. **로그 재동기화·쓰기 재개**: 최신 로그 복원 후 정상 쓰기 재개

#### 한줄 요약

- 분할 감지 후 **펜싱·쿼럼으로 단일 리더 확정**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **홀수 노드 구성(Odd Node Configuration)**: 최소 3대 이상의 홀수 노드를 배치하여 자동 과반수 합의를 구현하는 구성.
- **짝수 노드+증인 구성(Even Node with Witness)**: 2노드 환경에서 동률 방지를 위해 증인(Witness) 노드를 추가하는 구성.

</details>

| 클러스터 구성 | 홀수 노드 구성 (Odd Node) | 짝수 노드 + 증인 구성 (Even + Witness) |
|:---|:---|:---|
| 적용 기준 | 3대 이상의 표준 분산 클러스터 (Raft/Paxos) | 2대 노드 기반 Active-Standby 구성 시 |
| 핵심 특징 | 자체 과반수(N/2+1) 투표로 자동 동률 해결 | 데이터 미저장 증인(Witness) 노드로 캐스팅보트 행사 |
| 한계 | 인프라 비용 소요 (최소 3노드) | 증인 노드 장애 시 쿼럼 합의 불가 위험 |

> 요약: 홀수 노드 구성은 자체 과반수로 동률을 해소하며, 2노드 구성은 독립 증인 노드로 스플릿 브레인을 방지.

#### 한줄 요약

- 스플릿 브레인은 장애, **쿼럼은 단일 쓰기 통제**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **STONITH**: IPMI나 PDU를 통해 비정상 노드의 전원을 강제 차단하는 하드웨어 펜싱.
- **스토리지 펜싱(Storage Fencing)**: SCSI-3 PR 등을 활용해 노드의 스토리지 쓰기를 차단하는 논리 펜싱.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거짓 장애 탐지 | 다중 경로·적응형 타임아웃 | 불필요한 리더 전환 감소 |
| 쿼럼 손실 | 홀수 노드·독립 **AZ 증인** | 동률 해소와 쓰기 가용성 확보 |
| 오래된 리더 쓰기 | **펜싱·세대 번호** 검증 | 이전 임기의 오염 쓰기 차단 |

#### 한줄 요약

- 홀수 투표와 독립 **AZ 증인**으로 동률 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **쿼럼 기반 일관성 제어**: 과반수 합의와 강제 펜싱을 결합하여 단일 쓰기 원칙을 사수하는 설계 기조.

</details>

- 과반수 쿼럼 합의와 STONITH 펜싱 결합 기반 **단일 쓰기 및 데이터 정합성 보장**

#### 한줄 요약

- 일관성 우선 업무는 **과반 진영만 쓰기 허용**
