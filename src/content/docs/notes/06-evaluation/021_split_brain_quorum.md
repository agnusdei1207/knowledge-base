## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스플릿 브레인(Split-Brain)**: 클러스터 노드 간 통신 단절 시 다수의 노드가 스스로를 유일한 액티브 리더로 판단하여 데이터 충돌 및 정합성 훼손을 일으키는 현상.
- **네트워크 분할(Network Partition)**: 물리 노드는 정상 동작하나 상호 통신 링크가 단절되어 분할된 서브셋 간 상태 확인이 불가능해진 상태.
- **단일 쓰기 보장(Single-Leader Invariant)**: 네트워크 분할 상황에서도 유효한 단일 리더에게만 데이터 쓰기 권한을 허용하여 일관성을 보장하는 원칙.

</details>

- 정의/개념: 네트워크 분할로 복수 리더가 쓰는 **스플릿 브레인**
- 배경/필요성: 지연과 장애의 구분 실패로 **단일 쓰기 보장 불가**

#### 한줄 요약

- 분할 시 과반 진영만 쓰게 하는 **쿼럼 통제**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쿼럼(Quorum)**: 클러스터 내에서 리더 선출 및 트랜잭션 커밋 권한을 획득하기 위해 필요한 최소 과반수 투표 노드 수.
- **과반수 원칙(Majority Rule)**: 전체 노드 수(N)의 과반(N/2+1)을 획득한 그룹만 활성 상태를 유지하여 복수 리더 공존을 원천 차단하는 기법.
- **하트비트(Heartbeat)**: 노드 간 주기적으로 상태 확인 신호를 교환하여 장애 및 분할 여부를 실시간 탐지하는 메커니즘.
- **펜싱(Fencing)**: 쿼럼을 상실한 노드가 공유 스토리지에 쓰기를 시도하지 못하도록 전원 차단(STONITH)이나 볼륨 락을 통해 물리적/논리적으로 격리하는 기술.

</details>

- **과반수 쿼럼**으로 단일 리더 선출
- **펜싱**으로 이전 리더의 쓰기 차단
- **하트비트**•**증인**으로 네트워크 분할 판정

#### 한줄 요약

- 과반수 선출과 **펜싱**을 결합한 단일 쓰기 보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **증인/중재 노드(Witness/Arbiter Node)**: 데이터를 저장하지 않고 짝수 클러스터의 동률(Tie) 상황에서 캐스팅보트 투표권만 행사하는 보조 노드.
- **임대권(Lease)**: 정해진 시간 동안 특정 노드에만 쓰기 권한을 위임하여 쿼럼 만료 시 자동으로 리더 권한을 회수하는 시한부 권한 토큰.
- **세대 번호(Epoch/Term Number)**: 리더 선출 시마다 단조 증가하여 구 리더의 지연된 쓰기 요청을 식별하고 거부하는 시계열 번호.
- **동률 해소(Tie-Breaker)**: 2노드 클러스터 등 짝수 환경에서 과반수 합의 불가 문제를 해결하기 위해 도입하는 제3의 투표 메커니즘.

</details>

```text
[복제 노드•투표권]---[다중 하트비트•분할 감지]---[증인•중재 노드•쿼럼]
                              │                              │
                    [임대권•임기•세대]----------[펜싱•재동기화]
```

선의 의미: 감지·쿼럼·임대권·펜싱의 정적 통제 관계

| 구성요소 | 책임 |
|:---|:---|
| 복제 노드·투표권 | 리더 투표와 로그 복제 |
| 다중 하트비트·분할 감지 | 독립 경로와 타임아웃으로 장애 판정 |
| 증인·중재 노드·쿼럼 | **증인 노드**로 2노드 동률 해소 |
| 임대권·임기·세대 | **임대권·세대 번호**로 쓰기 권한 통제 |
| 펜싱·재동기화 | 이전 리더 차단과 최신 로그 복구 |

#### 한줄 요약

- 투표·증인·임대권·펜싱으로 **단일 쓰기 통제**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장애 감지(Failure Detection)**: 하트비트 연속 누락을 감지하고 일시적 지연과 실제 노드/네트워크 장애를 구분하는 단계.
- **선출 프로토콜(Election Protocol)**: 과반수 투표를 기반으로 새로운 단일 리더를 선출하고 세대 번호(Epoch)를 갱신하는 절차.
- **펜싱 실행(Fencing Execution)**: 구 리더의 전원을 차단하거나 스토리지 접근을 차단하여 뇌 분열 상태를 물리적으로 종식시키는 조치.

</details>

```text
       후보 노드
              │ 1. 분할 감지•새 임기 시작
              ▼
       쿼럼 관리자
              │ 2. 과반수 투표•로그 확인
              ▼
       펜싱 장치
              │ 3. 고립 노드 펜싱 실행
              ▼
       새 리더
              ├─ 4. 단일 임대권•리더 활성화
              └─ 5. 로그 재동기화•쓰기 재개
                          │
                          ▼
                합류 상태 무결 복구 턴
```

### 동작 원리

1. **분할 감지•새 임기 시작**: 분할 확인과 세대 번호 증가
2. **과반수 투표•로그 확인**: 과반수와 최신 로그 검증
3. **고립 노드 펜싱 실행**: 패배 노드의 **쓰기 차단**
4. **단일 임대권•리더 활성화**: 승자에게 **임대권** 발급
5. **로그 재동기화•쓰기 재개**: 최신 로그 복구 후 쓰기 재개

#### 한줄 요약

- 분할 감지 후 **펜싱**•**쿼럼**으로 단일 리더 확정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **홀수 노드 구성(Odd Node Configuration)**: 최소 3대 이상의 홀수 노드를 배치하여 증인 노드 없이도 항상 자연스러운 과반수 합의가 가능한 구성.
- **짝수 노드 구성(Even Node Configuration)**: 2노드 또는 짝수 노드 배치 시 동률 발생을 방지하기 위해 증인(Witness)이나 공유 디스크 쿼럼이 필수적인 구성.

</details>

**스플릿 브레인**은 장애, **쿼럼**은 방지 통제

| 구분 | 역할 | 결과·대가 |
|:---|:---|:---|
| 스플릿 브레인 | 복수 리더의 **동시 쓰기** | 데이터 분기·복구 비용 |
| 쿼럼 | 과반 진영의 **단일 쓰기** | 과반 미달 시 쓰기 중단 |

**Raft**•**Paxos**는 교차 과반수로 단일 합의값 보장

#### 한줄 요약

- 스플릿 브레인은 장애, **쿼럼은 단일 쓰기 통제**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **STONITH(Shoot The Other Node In The Head)**: IPMI 또는 PDU를 통해 비정상 노드의 전원을 강제 차단하여 데이터 오염 쓰기를 원천 차단하는 하드웨어 펜싱.
- **스토리지 펜싱(Storage Fencing)**: SCSI-3 Persistent Reservation 등을 활용하여 특정 노드의 스토리지 LUN I/O 등록을 취소/차단하는 논리적 펜싱.
- **네트워크 경로 이중화(Redundant Interconnect)**: 클러스터 전용 하트비트 망을 다중화하여 단일 링크 장애로 인한 오탐지 및 스플릿 브레인을 예방하는 네트워크 구성.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거짓 장애 탐지 | 다중 경로·적응형 타임아웃 | 불필요한 리더 전환 감소 |
| 쿼럼 손실 | 홀수 노드·독립 **AZ 증인** | 동률 해소와 쓰기 가용성 확보 |
| 오래된 리더 쓰기 | **펜싱·세대 번호** 검증 | 이전 임기의 오염 쓰기 차단 |

#### 한줄 요약

- 홀수 투표와 독립 **AZ 증인**으로 동률 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **쿼럼 기반 일관성 제어(Quorum-based Consistency Control)**: 과반수 합의와 강제 펜싱을 결합하여 어떠한 네트워크 분할 상황에서도 데이터 무결성과 단일 쓰기 원칙을 사수하는 클러스터 설계 기조.

</details>

- 금융·결제는 과반수·최신 로그·**펜싱 후 쓰기 허용**

#### 한줄 요약

- 일관성 우선 업무는 **과반 진영만 쓰기 허용**
