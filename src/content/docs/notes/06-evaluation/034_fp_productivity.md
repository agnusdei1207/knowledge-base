## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기능점수(Function Point, FP)**: 사용자 관점에서 소프트웨어가 제공하는 기능적 요구사항의 크기를 측정하여 수치화한 소프트웨어 규모 산정 표준 지표.
- **생산성 지표(Productivity Metric, FP/MM)**: 투입 공수(Man-Month)당 개발된 기능점수(FP)를 계산하여 개발 생산성과 효율성을 평가하는 지표.
- **소프트웨어 규모 산정(Software Sizing)**: 개발 언어나 구현 기술에 독립적으로 소프트웨어의 논리적 크기와 사업 대가를 객관적으로 산정하는 기법.

</details>

- 정의/개념: 사용자 기능을 계수하는 **기능점수 기반 규모·생산성** 산정
- 배경/필요성: LOC로는 착수 전 **규모·예산 예측 불가**

#### 한줄 요약

- 사용자 기능을 점수화해 **규모·FP/MM** 산정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 기능(Data Functions)**: 사용자가 요구하는 데이터를 저장하고 유지하기 위한 내부논리파일(ILF)과 외부연계파일(EIF).
- **트랜잭션 기능(Transactional Functions)**: 데이터를 입력, 출력, 조회하는 외부입력(EI), 외부출력(EO), 외부조회(EQ).
- **간이법/상세법(Average vs Detailed Method)**: 기획/발주 단계의 평균 복잡도 간이법과 분석/설계 단계의 요소별 가중치 상세법.
- **LOC 대비 독립성(Language Independence)**: 코드 라인 수(LOC)와 달리 개발 언어나 프레임워크에 영향을 받지 않는 객관적 규모 측정 보장.

</details>

- **애플리케이션 경계**로 내부·외부 데이터 구분
- 기능 유형별 개수와 가중치로 **UFP** 산출
- 기술 독립적 FP와 **MM**으로 생산성 비교

#### 한줄 요약

- 경계·중복 계수를 **동료 검토**로 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **내부논리파일(Internal Logical File, ILF)**: 애플리케이션 내부에서 유지·관리되는 주요 논리적 데이터 그룹.
- **외부연계파일(External Interface File, EIF)**: 다른 애플리케이션에서 유지되나 대상 시스템이 참조 목적으로 활용하는 데이터 그룹.
- **외부입력(External Input, EI)**: 외부에서 들어온 데이터나 제어 정보를 처리하여 내부논리파일을 갱신하는 트랜잭션.
- **외부출력(External Output, EO)**: 수학적 계산이나 파생 데이터를 생성하여 시스템 외부로 정보를 전송하는 트랜잭션.
- **외부조회(External Inquiry, EQ)**: 계산이나 파생 없이 단순 검색을 통해 외부로 데이터를 조회·출력하는 트랜잭션.

</details>

```text
                       [애플리케이션 경계]
                         /           \
                  [데이터 기능]   [트랜잭션 기능]
                         \           /
                      [복잡도 가중치]
                               |
                         [산정 기준]
```

선의 의미: 경계 안팎 기능에 복잡도 가중치를 적용

| 구성요소 | 책임 |
|:---|:---|
| 애플리케이션 경계 | 대상 범위와 데이터 관리 주체 확정 |
| 데이터 기능 | 내부 **ILF**와 외부 **EIF** 식별 |
| 트랜잭션 기능 | 입력 **EI**, 출력 **EO**, 조회 **EQ** 식별 |
| 복잡도 가중치 | DET·RET·FTR로 **UFP** 산출 |
| 산정 기준 | 공식 계수 규칙과 검토 이력 보존 |

#### 한줄 요약

- 경계별 **데이터·트랜잭션 기능**에 가중치 적용

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **측정 범위 및 경계 설정(Boundary Setting)**: 측정 대상 시스템의 범위와 외부 시스템과의 인터페이스 경계를 명확히 정의하는 단계.
- **데이터/트랜잭션 기능 식별(Function Identification)**: 사용자 요구사항 문서로부터 ILF, EIF, EI, EO, EQ 요소를 식별하고 목록화하는 단계.
- **복잡도 가중치 부여 및 미조정 FP 계산(UFP Calculation)**: 식별된 기능별 데이터 요소(DET)와 레코드/파일 요소(RET/FTR)를 기반으로 미조정 기능점수(UFP)를 산출하는 단계.
- **보정계수 적용 및 최종 FP 산출(AFP Calculation)**: 시스템 특성(분산 처리, 성능 요구, 보안 등) 보정계수를 적용하여 최종 기능점수를 확정하는 단계.

</details>

```text
산정자
   │ 1. 산정 목적•애플리케이션 경계 확정
   ▼
기능목록
   │ 2. 데이터•트랜잭션 기능 식별
   ▼
산정도구
   │ 3. 복잡도 가중치•FP 산출
   ▼
검토자
   │ 4. 경계•유형•누락 동료 검토
   ▼
산정자
   │ 5. 확정 FP•투입공수 생산성 산출
```

### 동작 원리

1. **산정 목적•애플리케이션 경계 확정**: 산정 수준과 경계 고정
2. **데이터•트랜잭션 기능 식별**: ILF·EIF·EI·EO·EQ 분류
3. **복잡도 가중치•FP 산출**: 기능별 가중치로 점수 산출
4. **경계•유형•누락 동료 검토**: 경계·분류·중복 교차 검증
5. **확정 FP•투입공수 생산성 산출**: 확정 FP를 MM으로 나눔

#### 한줄 요약

- FP는 규모, **FP/MM은 생산성** 지표

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정규 기능점수법(Detailed FP Analysis)**: 상세 설계 완료 후 각 기능의 DET/RET/FTR 개수를 세어 정확한 복잡도를 평가하는 기법.
- **간이 기능점수법(Average FP Analysis)**: 사업 초기나 제안 단계에서 기능 유형별 평균 복잡도 가중치를 적용하여 신속하게 규모를 추정하는 기법.

</details>

| 소프트웨어 규모 산정 방식 | 기능점수 (FP) | LOC (Lines of Code) | 스토리 포인트 (Story Point) |
|:---|:---|:---|:---|
| 적용 기준 | 견적·이기종 생산성 비교 | 구현 후 구조·결함 분석 | 팀 내부 스프린트 계획 |
| 핵심 특징 | 사용자 기능의 **논리 규모** | 코드 줄의 **물리 규모** | 주관적 상대 작업량 |
| 한계 | 경계 판정의 주관성 | 언어·생성 코드에 따른 변동 | 팀 간 비교 불가 |

> **생산성(Productivity) 도출 공식** = 프로젝트 총 확정 기능점수 (FP) / 개발 전체 투입 공수 (MM)

FP를 MM으로 나눈 **FP/MM**으로 개발 생산성을 산출한다.

#### 한줄 요약

- 계약·조직 비교에는 **FP/MM** 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **측정자 주관성 배제(Objectivity Assurance)**: 측정 기준 해석 차이로 인한 편차를 줄이기 위해 한국소프트웨어산업협회(KOSA) 소프트웨어 사업 대가산정 가이드 준수.
- **유지보수 및 변경 관리(Scope Creep Tracking)**: 프로젝트 진행 중 추가/변경된 기능점수를 정기 측정하여 개발 비용 및 일정 조정의 객관적 근거로 활용.
- **재사용 컴포넌트 평가(Reusable Component Sizing)**: 기존 프레임워크나 COTS 패키지 도입 시 재사용률에 따른 보정계수를 적용하여 과다 산정 방지.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **경계 오류·중복 계수** | 전문가 교차 검토 | 대가 산정 일관성 확보 |
| 환경 차이를 무시한 생산성 비교 | **비교 조건** 통제·보정 | 성과 평가 타당성 확보 |
| 요구 추가에 따른 규모 변동 | 베이스라인별 **변경 추적** | 계약 변경 근거 확보 |

#### 한줄 요약

- 확정 FP와 과거 **FP/MM**으로 필요 공수 산정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **표준 기반 객관적 소프트웨어 대가 산정(Standard-based Software Estimation)**: 기능점수를 기반으로 소프트웨어 사업의 적정 대가를 산정하고 프로젝트 생산성을 정량적으로 관리하는 핵심 기준.

</details>

- FP로 견적하고 동일 조건의 FP/MM으로 성과 평가

#### 한줄 요약

- **FP 규모·FP/MM 생산성**을 분리해 견적·성과 결정
