## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기능점수(FP: Function Point / IFPUG & KOSA 대가산정)**: 소프트웨어가 개발 언어나 기술 스택에 관계없이 사용자에게 제공하는 논리적 기능의 크기를 측정하기 위해, 데이터 기능(ILF: 내부논리파일, EIF: 외부연계파일)과 트랜잭션 기능(EI: 외부입력, EO: 외부출력, EQ: 외부조회)의 5개 영역으로 분류하고 복잡도(DET, RET, FTR)에 따른 가중치를 부여하여 소프트웨어 규모를 정량화하는 국제 표준 규모 측정 기법 (ISO/IEC 20926).
- **개발 생산성 (Productivity: FP/MM)**: 투입된 개발 공수 1 맨먼스(MM: Man-Month)당 완성된 기능점수(FP)의 양을 나타내는 개발 효율성 지표 ($\text{Productivity} = \frac{\text{총 기능점수 (FP)}}{\text{총 투입 공수 (MM)}}$).
- **LOC 기반 대가 산정의 언어 왜곡 및 기능 확장 결함(LOC Sizing Bias & Scope Creep Defect)**: 코드 라인 수(LOC)로 개발비를 책정하여 코드를 길고 비효율적으로 짤수록 돈을 더 받는 도덕적 해이가 발생하거나, 애플리케이션 경계(Boundary)가 모호하여 신규 요구사항이 추가될 때 공사비 증액 근거를 제시하지 못해 적자 프로젝트로 전락하는 구조적 결함.

</details>

- 정의/개념: 사용자 기능을 기준으로 규모를 재는 **기능점수** 산정 기법
- 배경/필요성: LOC로는 언어별 생산성과 **개발 대가 비교 불가**

#### 한줄 요약
- 기능점수(FP)는 사용자 관점에서 소프트웨어 규모를 측정하며, FP/MM 생산성을 통해 객관적 개발 공수와 예산을 산출한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **FP 5대 핵심 기능 유형 (Function Types)**:
  - **데이터 기능 (Data Functions)**:
    - **ILF (Internal Logical File, 내부논리파일)**: 시스템 내부에서 유지·관리되는 영속 데이터 그룹 (예: 회원 DB 테이블).
    - **EIF (External Interface File, 외부연계파일)**: 타 시스템에서 관리되나 본 시스템이 참조만 하는 데이터 그룹 (예: 연계 기관 코드 테이블).
  - **트랜잭션 기능 (Transaction Functions)**:
    - **EI (External Input, 외부입력)**: 외부에서 데이터가 인입되어 ILF를 생성/수정/삭제하는 기능 (예: 회원가입, 결제 승인).
    - **EO (External Output, 외부출력)**: 연산/계산 로직을 거쳐 파생 데이터를 외부로 출력하는 기능 (예: 월말 결산 리포트 출력).
    - **EQ (External Inquiry, 외부조회)**: 단순 검색을 통해 연산 없이 데이터를 조회하여 출력하는 기능 (예: 회원 정보 단순 조회).

</details>

- 구현 언어와 무관한 **사용자 기능 기반 규모**
- 기획은 평균 가중치의 **간이법**, 설계 후에는 상세법 적용
- 조직·프로젝트를 비교하는 **FP/MM 생산성**

#### 한줄 요약
- 5대 기능 유형(ILF/EIF/EI/EO/EQ), 기술 독립적 측정, 간이법/상세법 적용, 객관적 FP/MM 생산성 비교를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **기능점수 산정 3대 매트릭스 파라미터 (IFPUG 기준)**:
  - **DET (Data Element Type)**: 사용자가 식별 가능한 유일한 데이터 필드(컬럼) 수.
  - **RET (Record Element Type)**: ILF/EIF 내의 논리적 서브 레코드(하위 엔티티) 그룹 수.
  - **FTR (File Type Referenced)**: 트랜잭션 기능(EI/EO/EQ)이 참조하거나 갱신하는 ILF/EIF의 개수.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 애플리케이션 경계 및 5대 기능점수 분류 체계 (IFPUG Framework) ]    │
│                                                                         │
│  [ 타 시스템 (External System) ] ──(참조)── [ EIF (외부연계파일) ]      │
│                                                     │                   │
│ ┌──────────────────[ 본 애플리케이션 경계 (Boundary) ]──────┴─────────┐ │
│ │                                                                     │ │
│ │   [ 사용자 / 액터 ] ──(입력)── [ EI (외부입력) ] ── [ ILF (내부논리) ] │
│ │          ▲                                           │              │ │
│ │          │                                           ▼              │ │
│ │          ├───────────(연산 출력)── [ EO (외부출력) ] ──┘               │ │
│ │          │                                           │              │ │
│ │          └───────────(단순 조회)── [ EQ (외부조회) ] ──┘               │ │
│ └─────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 기능 유형별 복잡도 가중치 및 최종 기능점수 산출 공식 ]             │
├───────────────────┬──────────────┬──────────────┬───────────────────────┤
│ 기능 유형 구분    │ 낮음 (Low)   │ 보통 (Average)│ 높음 (High)           │
├───────────────────┼──────────────┼──────────────┼───────────────────────┤
│ **ILF (내부논리)**│ 7 점         │ **10 점**    │ 15 점                 │
│ **EIF (외부연계)**│ 5 점         │ **7 점**     │ 10 점                 │
│ **EI (외부입력)** │ 3 점         │ **4 점**     │ 6 점                  │
│ **EO (외부출력)** │ 4 점         │ **5 점**     │ 7 점                  │
│ **EQ (외부조회)** │ 3 점         │ **4 점**     │ 6 점                  │
└───────────────────┴──────────────┴──────────────┴───────────────────────┘
│  ├─ 미조정 기능점수: $UFP = \sum (\text{기능 개수} \times \text{가중치})$ │
│  └─ 보정 기능점수: $FP = UFP \times \text{규모보정} \times \text{연계보정} \times \text{성능보정}$│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 시스템 경계 내외의 데이터와 트랜잭션을 5개 기능으로 분류하고 각각의 복잡도 가중치를 곱해 최종 FP를 도출하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 애플리케이션 경계 | 내부·외부 기능의 **계수 범위** 확정 |
| ILF·EIF | 유지·참조하는 **데이터 기능** 계수 |
| EI·EO·EQ | 입력·출력·조회의 **트랜잭션 기능** 계수 |
| DET·RET·FTR | 기능별 **복잡도 가중치** 판정 |

#### 한줄 요약
- ILF(10), EIF(7), EI(4), EO(5), EQ(4)의 5대 기능과 DET/RET/FTR 복잡도 가중치로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **기능점수 산정 및 공수 도출 5단계 프로세스**:
  1. 소프트웨어 제안요청서(RFP) 분석을 통해 시스템 경계(Boundary) 확정
  2. 요구사항 명세서에서 데이터 기능(ILF, EIF)과 트랜잭션 기능(EI, EO, EQ) 목록 도출
  3. KOSA 간이법 가중치를 적용하여 미조정 기능점수(UFP) 합산
  4. 프로젝트 특성 보정계수(연계 복잡성, 다중 사이트)를 곱해 최종 보정 FP 확정
  5. 과거 조직 생산성(예: 15 FP/MM) 및 KOSA SW 단가를 대입하여 총 소요 공수(MM) 및 개발 예산 확정

</details>

```text
1. 애플리케이션 경계 확정
    ├─ 대상 프로젝트: 차세대 전자상거래 B2C 플랫폼 구축
    └─ [시스템 경계: 회원, 주문, 결제, 배송 모듈을 내부 경계로 확정]
            │
            ▼
2. 기능 유형 식별
    ├─ 데이터 기능: ILF 15개 (회원, 상품 등), EIF 5개 (PG 결제사, 택배사)
    └─ [트랜잭션 기능: EI 50개 (주문 등록 등), EO 20개 (정산서 등), EQ 30개 (상품 검색 등)]
            │
            ▼
3. UFP 산출
    ├─ ILF 점수: $15 \times 10.0 = 150 \text{ FP}$
    ├─ EIF 점수: $5 \times 7.0 = 35 \text{ FP}$
    ├─ EI 점수: $50 \times 4.0 = 200 \text{ FP}$
    ├─ EO 점수: $20 \times 5.0 = 100 \text{ FP}$
    ├─ EQ 점수: $30 \times 4.0 = 120 \text{ FP}$
    └─ [미조정 기능점수 합계: $UFP = 150 + 35 + 200 + 100 + 120 = 605 \text{ FP}$]
            │
            ▼
4. 보정 FP 확정
    ├─ 규모 보정: 1.0 (500~3,000 FP 구간)
    ├─ 연계 복잡성 보정: 1.06 (EIF 연계 다수)
    ├─ 최종 보정 기능점수: $FP = 605 \times 1.0 \times 1.06 = 641.3 \text{ FP}$
    └─ [최종 기능점수 확정: **641.3 FP**]
            │
            ▼
5. 공수·사업비 산출
    ├─ 조직 기준 개발 생산성: $15 \text{ FP/MM}$ (1인당 월 15 FP 개발)
    ├─ 총 필요 개발 공수: $\text{Effort} = \frac{641.3 \text{ FP}}{15 \text{ FP/MM}} = 42.75 \text{ MM}$
    ├─ 2026년 KOSA FP당 단가: 약 550,000원 대입
    └─ [순수 소프트웨어 개발비 확정: $641.3 \text{ FP} \times 550,000\text{원} = 352,715,000\text{원}$]
```

**동작 원리**

1. **애플리케이션 경계 확정**: 기능의 내부 유지·외부 참조 구분
2. **기능 유형 식별**: ILF·EIF·EI·EO·EQ 계수
3. **UFP 산출**: 기능 수에 복잡도 가중치 적용
4. **보정 FP 확정**: 사업 특성별 보정계수 반영
5. **공수·사업비 산출**: FP/MM 생산성과 단가 적용

#### 한줄 요약
- 경계 확정, 5대 기능 식별, 간이법 UFP 산출, 보정계수 적용, 생산성(FP/MM) 기반 공수/예산 확정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소프트웨어 규모 산정 3대 방식 비교**:
  - 기능점수 (Function Point): 사용자 논리 기능 측정 (국제 표준, 대가산정 기준).
  - 소스코드 라인 수 (LOC): 물리적 코드 줄 수 측정 (사후 결함 밀도 산정용).
  - 스토리 포인트 (Story Point): 애자일 스프린트 상대 난이도 측정 (팀 내부용).

</details>

| 비교 항목 | FP | LOC | 스토리 포인트 |
|:---|:---|:---|:---|
| 적용 기준 | 사용자 기능의 **사업 규모** | 구현 후 **코드량** | 팀 내부의 **상대 난이도** |
| 언어 영향 | **언어 독립적** | **언어 종속적** | **언어 독립적** |
| 측정 시점 | 기획·분석부터 **사전 측정** | 구현 후 **사후 측정** | 스프린트 전 **팀 추정** |
| 한계 | 경계 판정의 **전문성 필요** | 언어별 **생산성 왜곡** | 팀 간 **직접 비교 불가** |

#### 한줄 요약
- FP는 사용자 관점의 언어 독립적 법정 표준, LOC는 사후 물리 라인, 스토리 포인트는 애자일 상대 난이도이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **기능점수 실무 산정 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경계 오류로 **ILF·EIF 중복 계수** | CRUD 주체 기반 **경계 교차 검증** | **과대 산정** 방지 |
| 요구 추가로 **범위 증가** | 변경 시 **Change FP** 계수 | **계약 대가** 반영 |
| 알고리즘 난이도의 **FP 반영 한계** | 난이도 보정과 **투입공수 방식** 병행 | **특수 기술 원가** 보전 |

#### 한줄 요약
- CFPS 교차 검증으로 중복을 막고, 변경 FP로 과업 변경을 청구하며, 난이도 보정계수로 고난이도 기술을 보전한다.

## Ⅶ. 결론

- 사업 대가는 **FP**, 팀 계획은 **스토리 포인트**로 분리 적용

#### 한줄 요약
- IFPUG 기반 5대 기능점수 산정과 FP/MM 생산성을 통해 공정한 소프트웨어 대가 거버넌스를 완성한다.
