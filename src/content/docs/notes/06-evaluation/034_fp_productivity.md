## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기능점수(Function Point, FP)**: 사용자 관점에서 소프트웨어 기능적 요구사항의 크기를 측정하는 표준 지표.
- **생산성(Productivity, FP/MM)**: 투입 공수(Man-Month)당 개발된 기능점수(FP)를 나타내는 개발 효율성 지표.

</details>

- 정의/개념: 사용자 관점의 데이터 및 트랜잭션 기능을 측정하는 기능점수(FP)와 투입 공수당 개발량을 나타내는 FP/MM 생산성 산정 체계
- 배경/필요성: 코드 라인 수(LOC) 기반 산정의 언어 종속성과 사후 측정 한계를 극복하고 **개발 초기 객관적 규모 및 대가 산정** #### 한줄 요약

- 사용자 기능을 점수화해 **규모·FP/MM** 산정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 기능**: 시스템 내부/외부 데이터를 유지·참조하는 ILF(내부논리파일)와 EIF(외부연계파일).
- **트랜잭션 기능**: 사용자 요청을 처리하는 EI(외부입력), EO(외부출력), EQ(외부조회).

</details>

- **애플리케이션 경계** 기반 내부·외부 데이터 구분
- 기능 유형별 개수와 가중치로 **미조정 기능점수(UFP)** 산출
- 기술 독립적 FP와 **투입 공수(MM)** 기반 생산성 비교

#### 한줄 요약

- 경계·중복 계수를 **동료 검토** 기반 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ILF / EIF**: 시스템 내부 관리 파일(ILF) 및 타 시스템 참조 파일(EIF).
- **EI / EO / EQ**: 데이터 등록/수정(EI), 연산 후 출력(EO), 단순 검색(EQ).

</details>

```text
기능점수(FP) 산정 체계 (구조도)
├─ 애플리케이션 경계 식별: 시스템 범위 및 외부 인터페이스 정의
├─ 데이터 기능 식별: ILF(내부논리파일) / EIF(외부연계파일)
├─ 트랜잭션 기능 식별: EI(외부입력) / EO(외부출력) / EQ(외부조회)
└─ 복잡도 가중치 부여: DET/RET/FTR 개수 기준 UFP 산출 및 보정
```

선의 의미: 애플리케이션 경계 안팎의 데이터 및 트랜잭션 기능에 복잡도 가중치를 적용하는 기능점수 산정 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 애플리케이션 경계 | 대상 범위와 데이터 관리 주체 확정 |
| 데이터 기능 | 내부 **ILF** 및 외부 **EIF** 식별 |
| 트랜잭션 기능 | 입력 **EI**, 출력 **EO**, 조회 **EQ** 식별 |
| 복잡도 가중치 | DET·RET·FTR로 **UFP** 산출 |
| 산정 기준 | 공식 계수 규칙과 검토 이력 보존 |

#### 한줄 요약

- 경계별 **데이터·트랜잭션 기능** 대상 가중치 적용

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **간이법 vs 상세법**: 사업 초기 평균 복잡도를 적용하는 간이법과 설계 완료 후 DET/RET를 계수하는 상세법.

</details>

```text
       사업 분석가
              │ 1. 산정 목적 및 애플리케이션 경계 정의
              ▼
       기능 목록화
              │ 2. 데이터(ILF/EIF) 및 트랜잭션(EI/EO/EQ) 기능 식별
              ▼
       복잡도 산정
              │ 3. 유형별 가중치 부여 및 미조정 기능점수(UFP) 계산
              ▼
       전문가 검토
              │ 4. 경계 중복 및 누락 항목 교차 검증
              ▼
       공수/대가 산정
              │ 5. 최종 FP 확정 및 투입 공수(MM) 기반 생산성 도출
              ▼
        사업 대가 및 일정 확정
```

**동작 원리** 1. **경계 확정**: 대상 소프트웨어의 업무 범위와 타 시스템 간 연계 경계 설정
2. **기능 식별**: 사용자 요구사항에서 5가지 기능(ILF, EIF, EI, EO, EQ) 분류
3. **가중치 부여**: 각 기능의 데이터 요소(DET)와 레코드/파일 요소(RET/FTR) 기준으로 점수 계산
4. **교차 검토**: 측정자 간 편차를 줄이기 위해 동료 검토로 경계와 중복 계수 검증
5. **생산성 산정**: 최종 확정 기능점수를 투입 공수(MM)로 나누어 FP/MM 지표 산출

#### 한줄 요약

- FP는 규모, **FP/MM은 생산성** 지표

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **생산성 공식**: 생산성(FP/MM) = 프로젝트 총 확정 기능점수(FP) / 개발 투입 공수(MM)

</details>

| 소프트웨어 규모 산정 방식 | 기능점수 (Function Point) | 소스 코드 라인 (LOC) | 스토리 포인트 (Story Point) |
|:---|:---|:---|:---|
| 적용 기준 | 소프트웨어 사업 대가 산정 및 이기종 생산성 비교 | 개발 완료 후 소스 코드 구조 및 결함 밀도 분석 | 애자일 스프린트 내 팀별 상대적 작업량 추정 |
| 핵심 특징 | 사용자 관점의 논리적 기능 규모 측정 (언어 독립적) | 물리적 코드 라인 수 직접 계수 (언어 종속적) | 팀 내 주관적 난이도 기반 피보나치 수열 추정 |
| 한계 및 왜곡 | 측정자의 숙련도 및 경계 판정에 따른 편차 | 언어별 구현 방식 및 프레임워크에 따른 변동 | 서로 다른 개발팀 간 객관적 생산성 비교 불가 |

> **산식**: 개발 생산성 = 총 기능점수(FP) / 총 투입 공수(MM)

#### 한줄 요약

- 계약·조직 비교에는 **FP/MM** 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **KOSA 대가산정 가이드**: 한국소프트웨어산업협회의 공인 SW 사업 대가 산정 표준 지침.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경계 오류·중복 계수 | 전문가 교차 검토 | 대가 산정 일관성 확보 |
| 환경 차이를 무시한 생산성 비교 | **비교 조건** 통제·보정 | 성과 평가 타당성 확보 |
| 요구 추가에 따른 규모 변동 | 베이스라인별 **변경 추적** | 계약 변경 근거 확보 |

#### 한줄 요약

- 확정 FP와 과거 **FP/MM** 기반 필요 공수 산정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **소프트웨어 대가 거버넌스**: 기능점수를 기반으로 기획부터 개발, 변경 관리까지 일관된 사업 규모 및 비용을 통제하는 체계.

</details>

- 기능점수(FP) 기반 객관적 사업 대가 산정 및 **도메인별 FP/MM 기반 개발 공수 예측** #### 한줄 요약

- **FP 규모·FP/MM 생산성** 분리해 견적·성과 결정
