## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **애플리케이션 성능 관리(Application Performance Management, APM)**: 분산 아키텍처 내 요청 호출 경로와 자원 상태를 실시간 연계해 지연 원인을 추적·관리하는 모니터링 프레임워크.
- **관측성(Observability)**: 메트릭, 추적, 로그 등 외부 출력 신호로 시스템 내부 상태를 추론하는 역량.

</details>

- 정의/개념: 분산 환경의 트랜잭션 호출 경로와 자원 상태를 연계하여 성능 병목을 추적·관리하는 모니터링 체계
- 배경/필요성: 단순 자원 집계만으로는 **분산 트랜잭션 지연 원인** 식별 불가

#### 한줄 요약

- 분산 추적·자원 지표로 **구간별 병목 식별**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **추적 문맥(Trace Context)**: 단일 요청이 여러 서비스를 통과할 때 Trace ID와 부모 구간 정보를 헤더로 전달하는 메타데이터.
- **표본 추출(Sampling)**: 수집 오버헤드를 방지하기 위해 일정 비율의 요청만 상세 추적 로그로 저장하는 정책.
- **오픈텔레메트리(OpenTelemetry, OTel)**: 추적, 메트릭, 로그의 수집 및 전송 규격을 표준화한 오픈소스 관측성 프레임워크.
- **관측 비용 통제(Observability Cost Control)**: 표본율과 계측 심도를 튜닝해 CPU 부하와 스토리지 비용을 최적화하는 활동.

</details>

- **추적 문맥** 기반 MSA 종단 호출 관계 재조립
- **오픈텔레메트리** 기반 추적·메트릭·로그 연계
- **표본 추출·관측 비용 통제** 기반 오버헤드 제한

#### 한줄 요약

- 메트릭으로 탐지하고 추적으로 **병목 원인 격리**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **추적(Trace)**: 단일 요청이 여러 분산 노드를 거치며 남긴 종단 간 시계열 호출 궤적.
- **구간(Span)**: 단일 서비스 내 특정 메소드, API 호출, DB 질의의 실행 단위 기록.
- **메트릭(Metric)**: TPS, 지연시간, 오류율, 자원 이용률을 통계적으로 집계한 시계열 수치 데이터.
- **로그(Log)**: 런타임 상태 변이 및 오류 메시지를 Trace ID와 결합해 기록한 구조화 텍스트.
- **서비스 지도(Service Map)**: 구간 메타데이터를 기반으로 서비스 간 의존 관계와 트래픽 흐름을 시각화한 토폴로지 맵.

</details>

```text
                     [계측•추적 문맥]
                              |
                     [Span•Metric•Log]
                              |
                       [수집•처리 계층]
                              |
                    [시계열•추적 저장소] -- [분석•서비스 지도•알림]
```

선의 의미: 계측된 추적 문맥과 Span/Metric/Log가 수집·저장소를 거쳐 서비스 지도와 알림으로 통합 연계되는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 계측•추적 문맥 | Trace ID·부모 관계 전파 |
| Span•Metric•Log | **구간·메트릭·로그** 생성 |
| 수집•처리 계층 | 필터·표본·형식 변환 |
| 시계열•추적 저장소 | **추적·시계열 지표** 저장 |
| 분석•서비스 지도•알림 | **서비스 지도**·병목·알림 제공 |

#### 한줄 요약

- Trace ID로 **함수 지연·오류 경로 재조립**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **추적 식별자(Trace ID)**: 단일 사용자 트랜잭션이 여러 마이크로서비스를 통과하는 전 과정을 식별하는 전역 고유 식별자.
- **문맥 주입(Context Injection)**: 진입 게이트웨이에서 HTTP 헤더에 Trace ID와 상위 구간 정보를 삽입하는 단계.
- **이상 탐지(Anomaly Detection)**: 수집된 지연시간 통계를 바탕으로 지연 급증 및 슬로우 쿼리 구간을 판정하는 절차.

</details>

```text
클라이언트 요청
      │
      ▼
API 게이트웨이
   │ 1. W3C Trace Context 주입
   ▼
마이크로서비스
   │ 2. 하위 Span·Metric·Log 생성
   ▼
수집기(Collector)
   │ 3. 표본 추출 및 호출 경로 조립
   ▼
분석 엔진
   │ 4. 이상 탐지 및 병목 원인 분석
   ▼
성능 대시보드 및 경보
```

**동작 원리**

1. **W3C Trace Context 주입**: 진입점에서 전역 Trace ID 및 상위 부모 관계 생성 후 헤더 주입
2. **하위 Span·Metric·Log 생성**: 서비스별 비즈니스 로직 및 DB 쿼리 실행 구간 데이터 기록
3. **표본 추출 및 호출 경로 조립**: 수집기에서 동일 Trace ID를 매핑하여 종단 간 트리 구성
4. **이상 탐지 및 병목 원인 분석**: 슬로우 쿼리 및 지연 유발 컴포넌트의 근본 원인 도출

#### 한줄 요약

- Trace ID와 Span으로 **슬로우 쿼리와 API 지연 원인 추적**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **분산 추적(Distributed Traces)**: 개별 트랜잭션의 서비스 간 이동 궤적과 구간별 소요 시간을 심층 분석하는 기법.
- **집계 메트릭(Aggregated Metrics)**: CPU, 메모리, 처리량(TPS), 에러율을 일정 주기 단위로 집계하여 거시적 추세를 모니터링하는 기법.

</details>

| 관측 방식 | 분산 추적 (Traces) | 집계 메트릭 모니터링 (Metrics) |
|:---|:---|:---|
| 적용 기준 | **상세 병목 진단** 및 트랜잭션 추적 | **전체 시스템 이상 탐지** 및 추세 파악 |
| 핵심 특징 | 호출 경로 및 함수 수준 지연 분석 | 저비용 대시보드 및 알림 제공 |
| 한계 | 수집·저장 오버헤드 발생 | 구체적 지연 원인 및 코드 식별 불가 |

> 요약: 메트릭으로 이상 발생을 먼저 탐지하고, 분산 추적으로 세부 원인 구간을 상세 진단.

#### 한줄 요약

- 메트릭으로 탐지하고 **추적으로 상세 원인 분석**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **계측 오버헤드(Instrumentation Overhead)**: APM 에이전트 실행으로 인해 CPU 및 메모리 사용량이 증가하는 현상.
- **민감정보 마스킹(Sensitive Data Masking)**: 추적 로그 내 개인정보(PII) 및 인증 토큰을 비식별화 처리하는 보안 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이종 프레임워크 간 추적 헤더 유실 | **W3C Trace Context** 표준 규격 전파 | **호출 문맥 단절 방지** |
| 특정 상용 APM 솔루션 벤더 종속 | **OpenTelemetry** 표준 수집기 도입 | 백엔드 교체 유연성 확보 |
| 전수 계측으로 인한 성능 저하 및 보안 노출 | **표본 추출 및 민감정보 마스킹** 적용 | 계측 비용 절감 및 정보 보호 |

#### 한줄 요약

- 추적 문맥 보존과 **표본 추출 기반 계측 비용 통제**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **관측성 신호 연계(Telemetry Correlation)**: 메트릭, 로그, 추적 데이터를 단일 Trace ID와 시간 축으로 상호 연계하는 체계.

</details>

- 메트릭 이상 탐지 후 **분산 추적과 로그 연계 분석** 기반 근본 원인 해결

#### 한줄 요약

- 이상 메트릭을 **수정 가능한 구체적 호출 원인으로 전환**
