## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **APM(Application Performance Management)**: 요청 경로와 자원 지표를 연계하는 성능 관리 체계이다.
- **MSA(Microservices Architecture)**: 서비스를 독립 배포 단위로 분리한 구조이다.

</details>

- 정의/개념: **APM** — 애플리케이션 요청의 종단 경로를 추적하고 서비스•코드•질의•자원별 지연과 오류 원인을 분석하는 성능 관리 체계
- 배경/필요성: 집계 메트릭만으로는 **서비스•코드•질의 원인 식별 불가**

#### 한줄 요약
- 한 요청이 여러 서비스를 지나는 전 과정을 영수증처럼 기록해 어디서 오래 걸렸는지 찾습니다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **추적 문맥**: 추적 식별자와 부모 구간 정보를 서비스 간 요청에 전달하는 값이다.
- **표본 추출**: 일부 요청만 상세 추적하여 계측•저장 부하를 줄이는 방식이다.
- **오픈텔레메트리(OpenTelemetry)**: 추적•메트릭•로그의 생성•수집•전송을 지원하는 벤더 중립 관측성 체계이다.
- **관측 비용 통제**: 표본률과 계측 범위를 조절해 분석 가치와 처리•저장 오버헤드의 균형을 맞추는 활동이다.

</details>

- **인과 축**: 추적 문맥으로 종단 간 호출 관계 연결
- **신호 축**: 메트릭•추적•로그를 연계해 원인 진단
- **비용 축**: 표본률과 계측 오버헤드로 관측 비용 통제

#### 한줄 요약
- 지표로 느려졌다는 사실을 발견하고 Trace로 어느 호출이 느렸는지 좁히는 방식으로 함께 사용합니다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **추적(Trace)**: 하나의 요청이 여러 서비스를 거친 전체 호출 기록이다.
- **구간(Span)**: 추적 안에서 한 서비스나 외부 호출이 처리된 개별 기록이다.
- **메트릭**: 일정 시간 단위로 집계한 처리량•지연•오류•자원 사용 수치이다.
- **로그**: 특정 시점에 발생한 상태 변화•오류•업무 사건을 문맥과 함께 기록한 데이터이다.
- **서비스 지도**: 추적 구간의 부모•자식 관계를 조합해 서비스 의존성과 호출 방향을 나타낸 도식이다.

</details>

```text
                     [계측•추적 문맥]
                              |
                     [Span•Metric•Log]
                              |
                       [수집•처리 계층]
                              |
                    [시계열•추적 저장소] -- [분석•서비스 지도•알림]
```

선의 의미: 추적 문맥이 세 관측 신호를 결합하고 수집•처리 계층과 저장소를 거쳐 분석•서비스 지도•알림 영역에서 함께 참조되는 정적 APM 계층 구조

| 구성요소 | 책임 |
|:---|:---|
| 계측•추적 문맥 | **Trace ID•부모 관계** 전파 |
| Span•Metric•Log | **구간•집계•사건 텔레메트리** 생성 |
| 수집•처리 계층 | **수신•표본•변환•전송** 수행 |
| 시계열•추적 저장소 | **지표•호출 관계** 보관 |
| 분석•서비스 지도•알림 | **이상•병목•의존성** 가시화 |

#### 한줄 요약
- Trace ID로 흩어진 Span을 한 요청 경로로 연결하여 보여줍니다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **Trace ID(Trace Identifier)**: 한 요청에서 파생된 모든 호출을 연결하는 식별자이다.
- **W3C(World Wide Web Consortium)**: 웹 표준을 개발하는 국제 컨소시엄이다.
- **W3C Trace Context**: 분산 추적 문맥 전파를 표준화한 권고안이다.

</details>

```text
클라이언트
   │ API 요청·루트 Trace ID 생성
   ▼
게이트웨이
   │ 1. W3C Trace Context 주입
   ▼
하위 서비스
   │ 2. 하위 Span·Metric·Log 생성
   ▼
수집 계층
   │ 3. 표본·저장·호출 경로 조립
   ▼
분석기
   │ 4. 이상 탐지·병목 원인 분석
   ▼
이상 탐지·병목 원인 결과
```

**동작 원리**

1. **W3C Trace Context 주입**: 부모 관계•벤더 상태를 요청에 삽입
2. **하위 Span•Metric•Log 생성**: 지연•오류•자원 사건 기록
3. **표본•저장•호출 경로 조립**: 같은 Trace ID 구간 연결
4. **이상 탐지•병목 원인 분석**: 오류•지연 구간과 의존 호출 판별

#### 한줄 요약
- Trace ID와 Span 정보를 활용해 데이터베이스 쿼리나 외부 API 호출 중 느리거나 실패한 구간을 찾아냅니다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **요청 추적**: 개별 요청의 서비스•코드•질의 호출 경로와 시간을 분석하는 방식이다.
- **집계 메트릭**: 시간 구간별 수치를 합산하여 전체 이상 상태와 추세를 탐지하는 방식이다.
- **관측 방식 선택**: 집계 메트릭으로 전체 이상을 탐지하고 요청 추적으로 개별 호출의 병목 원인을 진단하는 구분이다.

</details>

| 성능 관측 방식 | APM 추적 분석 | 메트릭 모니터링 |
|:---|:---|:---|
| 적용 기준 | 상세 **병목 원인** 진단 | 전체 **이상 상태** 탐지 |
| 핵심 특징 | 요청별 **호출 경로** 분석 | 시간대별 **집계 수치** 분석 |
| 한계 | **계측•저장 오버헤드** | **개별 호출 원인** 누락 |

> 요약: **메트릭**으로 이상 탐지, **APM 추적**으로 원인 진단

#### 한줄 요약
- Metric은 집계 상태, Trace는 요청별 호출 경로를 보여 줍니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **CPU(Central Processing Unit)**: 명령을 해석•실행하는 중앙처리장치이다.
- **계측 오버헤드**: 계측이 추가하는 CPU•메모리•지연 비용이다.
- **표본률**: 전체 요청 중 상세 추적 데이터를 수집하도록 선택하는 비율이다.
- **민감정보 마스킹**: URL•헤더•질의에 포함된 개인정보•인증정보를 저장 전에 제거하거나 치환하는 조치이다.
- **호출 문맥 단절**: 서비스 사이에서 추적 헤더가 전달되지 않아 하나의 요청 경로가 여러 추적으로 분리되는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이기종 헤더가 달라지는 **호출 문맥 단절** | **W3C Trace Context** 적용 | 종단 호출의 **경로 연속성** 확보 |
| 전용 에이전트에 묶이는 **벤더 종속 계측** | **OpenTelemetry** 적용 | 수집기•백엔드의 **교체성** 향상 |
| 전량 추적으로 커지는 **비용•개인정보 노출** | **동적 표본•민감 속성 통제** | 저장 비용과 **노출 위험** 감소 |

#### 한줄 요약
- 분산 서비스 환경에서 호출 간 식별자 유실로 분석 경로가 끊어지는 현상을 모니터링합니다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **관측성 신호 연계**: 메트릭으로 이상을 찾고 추적과 로그로 같은 시점•요청의 원인을 좁히는 분석 방식이다.
- **종단 간 인과관계**: 서비스 간 부모•자식 호출을 연결하여 지연과 오류가 전파된 경로를 밝히는 관계이다.
- **진단 신호 선택**: 호출 원인은 분산 추적, 전체 이상 상태는 메트릭으로 확인하는 결정이다.

</details>

- 호출 원인은 **분산 추적**, 전체 이상 상태는 **메트릭**으로 진단

#### 한줄 요약
- 시스템 전체가 느리다는 경보를 실제 서비스•쿼리•외부 호출의 개선 과제로 바꾸어 줍니다.
