## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **결함 허용 시스템(FTS: Fault-Tolerant System / Non-Stop & Continuous Availability)**: 시스템 내부의 CPU, 메모리, 버스, 전원 등 특정 하드웨어 부품이나 소프트웨어 컴포넌트에 물리적·논리적 고장이 발생하더라도, 하드웨어 락스텝(Lockstep) 동기화 및 다수결 표결(TMR: Triple Modular Redundancy)을 통해 결함을 사용자 모르게 실시간 마스킹(Masking)하여, 서비스 중단(Downtime=0)이나 세션 단절, 트랜잭션 유실 없이 정상 연산을 100% 지속하는 최고 수준의 신뢰성 컴퓨팅 아키텍처.
- **고가용성(HA) 페일오버의 순간 단절 한계 결함(HA Failover Glitch Defect)**: 일반적인 고가용성(HA) 클러스터는 장애 발생 시 감지$\cdot$승격$\cdot$VIP 이전 과정에서 수 초~수십 초의 세션 끊김과 트랜잭션 롤백이 불가피하여, 우주항공 제어, 원자력 발전, 증권 거래소 체결 엔진 등 단 1밀리초의 중단도 인명 피해나 수천억 원의 금융 사고로 직결되는 미션 크리티컬 환경에 적용할 수 없는 구조적 한계.

</details>

- 정의/개념: 인명 안전 및 금융 무손실을 절대적으로 보증하기 위해 **하드웨어 락스텝 병렬 연산 $\rightarrow$ 삼중 모듈 중복(TMR) 기반 2:1 다수결 표결 $\rightarrow$ 결함 즉시 마스킹(Fault Masking) $\rightarrow$ 비정상 모듈 버스 펜싱(Containment) $\rightarrow$ 무중단 핫스왑(Hot-swap) 온라인 부품 교체 및 재통합** 을 집행하는 **연속 가용성(Continuous Availability) 엔지니어링 체계**
- 배경/필요성: 금융망 코어 체결, 철도 신호 제어, 자율주행 전자제어(ECU), 의료 생명유지 장치에서 장애 발생 시 페일오버 대기 시간을 허용하지 않고 즉시 정상 출력을 유지할 수 있는 결함 감내 체계 필수화

#### 한줄 요약
- 결함 허용 시스템(FTS)은 락스텝과 TMR 다수결 표결을 통해 부품 고장 시에도 다운타임 0초로 무중단 연산을 지속한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **FTS 4단계 결함 처리 수명주기**:
  - **1단계: 결함 감지 (Fault Detection)**: 비트 단위 비교기로 이상 출력을 나노초 단위로 식별.
  - **2단계: 결함 마스킹 (Fault Masking)**: 3개 중 2개 정상 모듈의 출력을 다수결로 채택하여 외부로 정상 출력 전송.
  - **3단계: 결함 격리 (Fault Containment)**: 고장 모듈을 시스템 버스에서 즉각 전기적으로 분리하여 오염 전파 차단.
  - **4단계: 결함 복구 (Fault Recovery)**: 전원을 끄지 않고 신규 모듈을 핫스왑 장착 후 메모리 상태를 동기화하여 TMR 복원.

</details>

- **결함의 투명한 마스킹(Transparent Masking)**: 부품이 타버리거나 비트 반전이 발생해도 표결기(Voter)가 정상 출력을 내보내므로 OS나 애플리케이션은 장애 발생 사실조차 인지하지 못함
- **클록 단위 하드웨어 락스텝(Cycle-by-Cycle Lockstep)**: 2개 또는 3개의 CPU가 동일한 클록 신호에 맞춰 1나노초의 오차도 없이 동일 명령어를 병렬 실행하고 비교
- **무정지 온라인 핫스왑(Online Hot-Swapping)**: 서버 섀시를 끄지 않고 고장 난 CPU/메모리 보드를 슬롯에서 발거하고 새 보드를 삽입하여 100% 온라인 중복성 회복

#### 한줄 요약
- 4단계 결함 처리(감지/마스킹/격리/복구), 클록 단위 락스텝 연산, 투명한 TMR 표결, 무정지 핫스왑을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **FTS 핵심 3대 모듈 중복(TMR: Triple Modular Redundancy) 아키텍처**:
  1. **Input Replicator**: 입력 데이터를 3개 독립 모듈로 클록 동기화 분기.
  2. **Triple Execution Units**: 모듈 A, B, C (독립 전원, 독립 CPU/RAM, 락스텝 실행).
  3. **Majority Voter (다수결 표결기)**: 2개 이상의 일치 값을 최종 출력으로 채택 ($V = AB + BC + CA$).
  4. **Fault Diagnostic & Recovery Controller**: 고장 모듈 격리 및 핫스왑 재동기화 통제.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 입력 복제 및 락스텝 분배 (Synchronous Input Distribution) ]         │
│  └─ [ 클라이언트 트랜잭션 입력 신호 (Instruction Stream) ]               │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (3개 독립 연산 모듈로 동시 분기)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 삼중 모듈 락스텝 병렬 연산 계층 (Triple Modular Execution: TMR) ]  │
├───────────────────┬───────────────────┬─────────────────────────────────┤
│ [ 모듈 A (정상) ] │ [ 모듈 B (정상) ] │ [ 모듈 C (하드웨어 비트 결함) ] │
│ ├─ 독립 CPU / RAM ├─ 독립 CPU / RAM   ├─ 독립 CPU / RAM                 │
│ └─ 출력값: `0xFA` └─ 출력값: `0xFA`   └─ 출력값: `0x00` (이상 출력 발생)│
└───────────────────┴───────────────────┴─────────────────────────────────┘
                                     │ (하드웨어 표결기로 3개 출력 동시 인입)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 다수결 표결기 및 결함 마스킹 (Majority Voter: Output = AB + BC + CA) ]│
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ 2:1 다수결 판정: (A: 0xFA == B: 0xFA) != (C: 0x00)                 │  │
│  │ 최종 정상 출력: `0xFA` (다운타임 0초, 세션 단절 0건으로 외부 전송)│  │
│  └───────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (결함 진단 및 온라인 복구)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 결함 격리 및 핫스왑 재통합 (Fault Containment & Hot-Swap Sync) ]   │
│  ├─ [ 모듈 C 버스 신호 즉각 차단 (Containment) ] ➔ LED 적색 점등         │
│  └─ [ 온라인 핫스왑 보드 교체 ➔ 메모리 미러링 동기화 ➔ TMR 3중화 복원 ] │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 동일 입력을 3개 모듈이 동시 실행하고 다수결 표결기가 정상 값을 선택하여 출력하며, 고장 모듈은 즉시 분리 후 핫스왑 복원하는 구조

| FTS 핵심 컴포넌트 | 수학적 모델 및 역할 | 주요 기술 메커니즘 | 비고 |
|:---|:---|:---|:---|
| **입력 분배기** | 동일 클록 사이클에 3개 모듈로 데이터 복제 전달 | Phase-Locked Loop (PLL), 클록 동기화 | Input |
| **삼중 연산 모듈 (TMR)**| 완전히 독립된 3개의 프로세서 및 메모리에서 병렬 연산 | Stratus ftServer, Tandem NonStop | Execution |
| **다수결 표결기 (Voter)**| $Out = (A \land B) \lor (B \land C) \lor (C \land A)$ 불 대수 연산 | 고속 하드웨어 ASIC / FPGA 로직 | Masking |
| **결함 진단 제어기** | 3개 출력 중 불일치 모듈을 나노초 단위로 특정 | Parity Check, Signature Analysis | Detection |
| **온라인 핫스왑 슬롯**| 전원 차단 없이 고장 보드 탈착 및 신규 보드 장착 | Hot-Plug PCI-e, 전원 서지 방지 회로 | Recovery |

#### 한줄 요약
- 입력 분배기, TMR 삼중 연산 모듈, 다수결 표결기, 결함 진단 제어기, 온라인 핫스왑 슬롯으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **FTS 결함 감내 및 무중단 복구 5단계 프로세스**:
  1. 클라이언트 주식 매수 주문이 TMR 시스템으로 인입
  2. 모듈 A, B, C가 클록 락스텝으로 매수 체결 연산 동시 실행
  3. 모듈 C의 RAM 칩 불량으로 잘못된 체결 금액(0원) 연산 출력
  4. 다수결 표결기가 2:1로 모듈 A, B의 정상 금액을 선택하여 거래소로 즉각 전송 (다운타임 0초)
  5. 모듈 C를 전기적으로 격리 후 엔지니어가 무정지 핫스왑으로 보드 교체 완료

</details>

```text
1. [실시간 트랜잭션 입력 및 분배]
    ├─ 증권 체결 엔진으로 "주식 1,000주 시장가 매수" 트랜잭션 인입
    └─ [입력 버스가 동일 명령어를 모듈 A, 모듈 B, 모듈 C로 동시 브로드캐스트]
            │
            ▼
2. [클록 락스텝 병렬 실행]
    ├─ 3개 모듈이 동일한 3.0GHz 클록에 맞춰 나노초 단위로 동시 명령어 연산
    └─ [모듈 A: `정상 체결 50,000원`, 모듈 B: `정상 체결 50,000원` 산출]
            │
            ▼
3. [단일 모듈 물리 결함 발생 및 감지]
    ├─ 모듈 C의 메모리 셀에 우주선(Cosmic-ray)에 의한 비트 플립 결함 발생
    ├─ 모듈 C의 연산 결과: `비정상 체결 0원` 산출 (오류 발생)
    └─ [표결기 입력단에 A(50,000), B(50,000), C(0) 동시 도착]
            │
            ▼
4. [TMR 다수결 표결 및 결함 마스킹]
    ├─ 표결기 로직: $(A == B) \rightarrow \text{True}$ 판정
    ├─ 정상 결과 `50,000원`을 증권 거래소 대외망으로 즉시 출력 (소요 시간: 0초)
    └─ [결과: 사용자 및 증권사 시스템은 장애 발생 사실을 전혀 인지하지 못함 (완전 무결)]
            │
            ▼
5. [결함 모듈 격리 및 무정지 핫스왑 복구]
    ├─ 진단기가 모듈 C의 에러를 기록하고 시스템 버스 연결을 전기적으로 절체(Isolation)
    ├─ 데이터센터 기사가 서버 전원을 끄지 않고 모듈 C 슬롯을 뽑아 새 보드로 장착
    └─ [메인보드가 모듈 A/B의 메모리 데이터를 새 보드로 실시간 복사 ➔ TMR 3중화 100% 복원]
```

**동작 원리**

1. **지연 시간 없는 결함 마스킹(Zero-latency Masking)**: 결함을 고치기 위해 멈추거나 백업 서버를 깨우는 것이 아니라, 3개의 실행 결과 중 다수결을 하드웨어 로직 게이트에서 즉시 뽑아내므로 지연이 0나노초에 수렴
2. **소프트웨어 레벨 FTS (N-Version Programming)**: 하드웨어뿐만 아니라 소프트웨어 버그를 감내하기 위해 서로 다른 3개 개발팀이 서로 다른 언어로 구현한 3개의 알고리즘 결과를 표결하는 기법 적용
3. **공통 원인 고장(CCF)의 물리적 방어**: 3개 모듈의 전원 공급 장치(Power Supply), 쿨링 팬, 클록 발생기를 완전히 독립 분리하여 단일 전원 고장 시 동시 정지 차단
4. **페일-세이프(Fail-Safe) 연계**: 만약 3개 모듈 중 2개가 동시에 고장 나 다수결 합의가 불가능해질 경우, 시스템이 잘못된 값을 출력하지 않고 안전 상태(신호등 적색 점등)로 즉각 정지
5. **IEC 61508 SIL 4 최고 등급 준거**: 원자력 및 철도 안전 표준에서 요구하는 위험 발생 확률 $10^{-9}/\text{hour}$ 이하의 극단적 신뢰도 달성

#### 한줄 요약
- 트랜잭션 분배, 락스텝 병렬 실행, 단일 모듈 결함 발생, TMR 다수결 표결/마스킹, 무정지 핫스왑 복원 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **가용성/신뢰성 아키텍처 2대 패러다임 비교**:
  - 결함 허용 시스템 (FTS: Fault Tolerant): 고장 중에도 서비스가 멈추지 않고 연산 지속 (다운타임 0초).
  - 고가용성 시스템 (HA: High Availability): 고장 발생 시 대기 노드로 전환하여 복구 (다운타임 수 초~수 분).

</details>

| 비교 항목 | 결함 허용 시스템 (Fault-Tolerant: FTS) | 고가용성 시스템 (High Availability: HA) |
|:---|:---|:---|
| **복구 메커니즘** | **하드웨어 락스텝 및 TMR 다수결 결함 마스킹**| **장애 감지(Health-check) 후 Standby Failover**|
| **복구 시간 (RTO)**| **0초 (Zero Downtime, 완전 무중단)** | **수 초 ~ 수 분 (전환 및 기동 시간 소요)** |
| **데이터 손실 (RPO)**| **0초 (Zero Data Loss, 트랜잭션 보존)** | 0초 ~ 수 분 (비동기 복제 시 유실 가능) |
| **세션 연속성** | **세션 끊김 0건 (진행 중인 커넥션 100% 유지)**| **세션 일시 단절 (재로그인 또는 재연결 필요)** |
| **인프라 비용** | **초고가 ($5\times \sim 10\times$, 전용 하드웨어)** | **경제적 ($1.5\times \sim 2\times$, 범용 x86 서버)** |
| **적용 분야** | **우주항공, 원자력 제어, 증권 거래소 체결** | **일반 이커머스, 사내 포털, 웹 서비스** |

#### 한줄 요약
- FTS는 락스텝 표결 기반의 무중단 무손실(RTO=0, RPO=0), HA는 헬스체크 기반의 페일오버 복구이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **FTS 구축 및 실무 운영 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 3개 모듈의 출력을 최종 취합하는 단일 표결기(Majority Voter)가 고장 나서 **시스템 전체가 셧다운되는 치명적 표결기 SPOF 발생** | **다수결 표결기 자체를 3중화(Triplicated Voters)하여 각 모듈로 독립 피드백하는 완전 분산 표결 아키텍처 구현** | 단일 표결기 고장에 의한 단일 장애점 100% 제거 |
| 동일한 소프트웨어 버그(예: Divide by Zero)로 인해 **3개의 락스텝 모듈이 동일한 시점에 동시 크래시되어 TMR이 무력화** | **서로 다른 컴파일러와 서로 다른 알고리즘으로 독립 개발된 N-Version Programming 및 회복 블록(Recovery Block) 소프트웨어 적용** | 공통 소프트웨어 버그에 의한 동시 중단 방어 |
| 일반 사내 웹 시스템에 무조건 FTS를 도입하여 **수십억 원의 전용 하드웨어 도입 비용과 유지보수 라이선스로 극심한 예산 낭비 발생** | **IEC 61508 기능 안전성 및 비즈니스 위험도 평가(BIA)를 수행하여 SIL 4급 미션 크리티컬 영역에만 FTS를 선별 도입** | 인프라 투자 대비 최고의 ROI 및 안전성 달성 |

#### 한줄 요약
- 표결기를 3중화하여 SPOF를 없애고, N-Version 소프트웨어로 버그를 막으며, SIL 4 영역에만 선별 도입한다.

## Ⅶ. 결론

- 단 1밀리초의 중단이나 데이터 손실도 절대 용납되지 않는 극한의 미션 크리티컬 환경을 지탱하는 최고 수준의 신뢰성 컴퓨팅 공학인 **결함 허용 시스템(FTS) 체계**는 결함을 사후 복구하는 것이 아니라 하드웨어 레벨에서 실시간으로 마스킹하는 궁극의 연속 가용성 아키텍처이며, 실무 구현 시 **클록 동기화 락스텝 및 TMR 2:1 다수결 표결 구조 완비**, **4단계 결함 처리(감지$\cdot$마스킹$\cdot$격리$\cdot$복구) 라이프사이클 내재화**, **표결기 3중화 및 무정지 핫스왑 복원성 확보**, **IEC 61508 기능 안전 표준 준거**를 완성하여 최고 수준의 무결점 연속 가용성과 절대적 시스템 신뢰성을 완성

#### 한줄 요약
- 락스텝 TMR 다수결 표결과 무정지 핫스왑을 통해 결함 발생 시에도 다운타임 0초의 완전한 연속 가용성을 완성한다.
