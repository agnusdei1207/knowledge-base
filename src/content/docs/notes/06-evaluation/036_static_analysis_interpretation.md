## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **정적 분석 결과 해석**: 정적 도구가 검출한 경고에 대해 실제 런타임 도달성과 오염 흐름을 분석하여 조치 우선순위를 판정하는 활동.
- **참 양성(True Positive, TP)**: 정적 도구의 경고 중 실제 런타임에 결함이나 취약점으로 발현되는 진짜 결함.
- **거짓 양성(False Positive, FP)**: 실제로는 결함이 아니거나 방어 로직으로 인해 공격 불가능한 오탐 경고.

</details>

- 정의/개념: 정적 분석 도구가 검출한 수많은 경고에 대해 오염 흐름(Taint Flow)과 도달 가능성을 검증하여 참 양성(TP)과 거짓 양성(FP)을 판별하는 분석 활동
- 배경/필요성: 단순 경고 건수 집계의 한계를 극복하고 **오탐(FP) 제거 및 실제 치명적 보안 취약점에 대한 수정 집중**

#### 한줄 요약

- 도달성과 피해로 **참 양성·거짓 양성** 판정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **오염 흐름(Taint Flow)**: 외부 입력값(Source)이 필터링 없이 위험 함수(Sink)까지 전달되는 데이터 이동 궤적.
- **도달 가능성(Reachability)**: 외부 요청이 실제 런타임 제어 흐름을 타고 취약점 코드 블록까지 도달할 수 있는지의 여부.

</details>

- 룰셋·빌드 환경 고정으로 **재현성** 확보
- **오염 흐름·도달 가능성** 기반 런타임 위험 판정
- 분류 검토와 만료형 **예외 승인** 적용

#### 한줄 요약

- **Source-Sink 오염 흐름** 및 통제 유효성 검증

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **트리아지(Triage)**: 도구가 생성한 경고 목록을 검토하여 TP/FP 및 심각도를 선별 분류하는 전문 심사 작업.
- **품질 게이트(Quality Gate)**: 미해결 Critical/High 등급 취약점이 존재할 때 CI/CD 배포를 자동 중단하는 통제 장치.

</details>

```text
정적 분석 판정 및 트리아지 체계 (구조도)
├─ 입력 소스/환경: 소스 코드 / 빌드 환경 / 공인 룰셋 버전 고정
├─ 정적 분석 엔진: AST 파싱 / 제어 흐름(CFG) / Taint 데이터 흐름 분석
├─ 경고 저장소: 스캔 결과 / Source-Sink 경로 / 과거 판정 이력(Audit Trail)
└─ 트리아지/게이트: 전문가 TP/FP 판정 / 만료형 Waiver / 배포 차단 품질 게이트
```

선의 의미: 분석 입력부터 엔진 스캔, 경고 저장 및 트리아지 검토를 거쳐 품질 게이트로 이어지는 정적 분석 판정 체계.

| 구성요소 | 책임 |
|:---|:---|
| 분석 입력 | 소스·빌드 환경·**룰셋 버전** 고정 |
| 정적 분석 엔진 | 제어·**오염 흐름** 기반 경고 생성 |
| 경고 저장소 | 위치·경로·심각도·**판정 이력** 보관 |
| 분류 검토 | **TP**·**FP** 및 위험 수용 판정 |
| 품질 게이트 | 미해결 고위험 TP의 배포 차단 |

#### 한줄 요약

- TP·FP 판정 후 **고위험 TP 배포 차단**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **위험 수용(Waiver)**: 즉각 수정이 어려운 TP 항목에 대해 WAF 보완 통제 적용 후 기한부로 승인하는 조치.

</details>

```text
       정적 분석 도구
              │ 1. 소스 코드 스캔 및 Source-Sink 오염 경로 검출
              ▼
       보안/품질 전문가
              │ 2. 런타임 도달 가능성 및 살균(Sanitizer) 로직 유효성 검증
              ▼
       트리아지 심사
              │ 3. 진짜 결함(TP) vs 단순 오탐(FP) vs 위험 수용(Waiver) 분류
              ▼
       품질 게이트
              │ 4. 고위험 TP 배포 차단 / FP 룰셋 예외 처리 / 조건부 배포 승인
              ▼
        소스 패치 및 안전한 배포 완료
```

**동작 원리**

1. **오염 스캔**: 외부 입력(Source)부터 치명적 실행(Sink)까지의 데이터 전파 경로 식별
2. **도달성 검증**: 중간 유효성 검증 로직 및 네트워크 방화벽 등 보완 통제 유무 분석
3. **상태 분류**: 실제 익스플로잇 가능 여부에 따라 TP, FP, Waiver로 분류
4. **게이트 연계**: 미조치된 고위험 TP가 존재할 경우 빌드 및 상용 배포 파이프라인 차단
5. **예외 관리**: 승인된 Waiver 항목은 만료일(3~6개월)을 지정하여 주기적 재검증

#### 한줄 요약

- 오염 경로를 판정해 **수정·예외·배포** 결정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도구 심각도 vs 업무 위험도**: 도구가 부여한 기계적 등급(High/Medium)과 실제 자산 가치 및 침해 영향을 결합한 현실적 위험도.

</details>

| 판정 구분 | 참 양성 (True Positive) | 거짓 양성 (False Positive) | 위험 수용 (Risk Acceptance) |
|:---|:---|:---|:---|
| 적용 기준 | 런타임 도달 가능한 실제 보안 취약점 | 방어 로직이 존재하여 공격 불가능한 오탐 | 구조적 한계로 즉시 수정 불가한 취약점 |
| 핵심 조치 | 소스 코드 즉각 패치 및 재검증 | 오탐 사유 문서화 및 예외 룰 등록 | WAF 등 보완 통제 적용 및 기한부 승인 |
| 한계 | 미조치 시 런타임 침해 사고 직결 | 과도한 FP 발생 시 개발 생산성 저하 | 영구 예외 방치 시 장기적 보안 부채 누적 |

> **원칙**: 참 양성(TP)과 거짓 양성(FP)을 먼저 판별하고, 확인된 TP는 즉각 수정하거나 기한부 위험 수용(Waiver) 적용.

#### 한줄 요약

- 도달 가능한 **고영향 TP** 활용 최우선 조치

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **예외 지시어(@SuppressWarnings)**: 오탐으로 판명된 코드에 주석을 달아 차기 스캔부터 경고를 숨기는 키워드.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 환경 없는 **도구 심각도** 맹신 | 전문가 **분류 검토** | 실제 위험에 수정 공수 집중 |
| **예외 지시어 남용** | 사유·교차 검토·**예외 만료** | 영구 취약점 은폐 방지 |
| 룰셋·환경 변경의 기준선 붕괴 | 분석 환경·엔진 버전 고정 | 분석 **재현성** 확보 |

#### 한줄 요약

- Source-Sink 도달은 TP, 유효한 정제는 **FP 근거**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DevSecOps 정적 거버넌스**: 무의미한 경고 수 대신 실제 침해 위험이 높은 취약점을 선별하여 자동 차단하고 지속 관리하는 체계.

</details>

- 도달 가능성 및 비즈니스 영향도 기반 **고위험 참 양성(TP) 즉각 조치 및 만료형 예외 관리**

#### 한줄 요약

- **도달성·피해 규모** 기반 수정·차단·예외 결정
