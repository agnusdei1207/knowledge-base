## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **정적 분석 결과 해석**: 프로그램을 실행하지 않고 찾은 경고의 도달 가능성•오염 흐름•업무 영향을 검토해 실제 결함 여부와 조치 우선순위를 판정하는 활동이다.
- **분류 검토**: 도구 경고의 사실 여부•도달 가능성•영향과 조치 우선순위를 사람이 판정하는 활동이다.
- **오탐**: 분석 도구가 문제로 경고했지만 실행 문맥과 보호 통제를 확인했을 때 실제 결함은 아닌 항목이다.

</details>

- 정의/개념: 경고의 도달•오염•업무 영향으로 결함을 판정하는 **정적 분석 결과 해석**이다.
- 배경/필요성: 도구 심각도•경고 수만으로는 **오탐**과 실제 결함을 구분하기 어렵다.

#### 한줄 요약
- 실제 실행 경로와 피해를 확인한 정적 분석 경고의 수정 우선순위를 결정한다.


## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **룰셋**: 결함이나 취약점 유형을 찾기 위해 적용하는 탐지 규칙의 묶음이다.
- **도달 가능성**: 실제 입력과 실행 조건에서 경고 지점까지 제어 흐름이 이어질 가능성이다.
- **오염 흐름**: 신뢰할 수 없는 입력이 적절한 검증 없이 위험 함수까지 이동하는 데이터 경로이다.
- **재현성**: 같은 소스•의존성•빌드 환경•룰셋으로 다시 분석했을 때 같은 경고를 얻을 수 있는 성질이다.

</details>

- **룰셋**과 빌드 환경을 고정해 **재현성**을 확보한다.
- **도달 가능성**과 **오염 흐름**으로 실제 위험을 판정한다.
- 분류 검토와 예외 만료로 미해결 위험을 통제한다.

#### 한줄 요약
- 외부 입력의 도달성과 업무 영향에 따른 수정•예외를 처리한다.


## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **참 양성(True Positive, TP)**: 분석 도구가 경고한 항목에 실제 결함이나 취약점이 존재하는 판정이다.
- **거짓 양성(False Positive, FP)**: 도구가 경고했지만 실행 문맥과 보호 통제를 검토했을 때 실제 문제는 없는 판정이다.
- **심각도**: 경고한 문제가 발생했을 때 예상되는 피해 수준이다.
- **신뢰도**: 도구가 탐지 결과를 실제 문제라고 판단하는 확신 수준이다.
- **판정 이력**: 경고별 검토 결과•근거•승인•변경 내역을 추적할 수 있게 보존한 기록이다.

</details>

```text
정적 분석 판정 체계
├─ 분석 입력
├─ 정적 분석 엔진
├─ 경고 저장소
├─ 분류 검토
└─ 품질 게이트
```

선의 의미: 고정된 분석 입력과 경고 증거를 분류 검토와 배포 통제에 연결한 정적 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 분석 입력 | 소스•바이트코드•빌드 환경과 룰셋 버전 고정 |
| 정적 분석 엔진 | 구문•제어•데이터 흐름 경고 생성 |
| 경고 저장소 | 코드 위치•오염 경로•심각도•**판정 이력** 보관 |
| 분류 검토 | **참 양성**, **거짓 양성**, 위험 수용 판정 |
| 품질 게이트 | 신규 미해결 고위험 경고 차단 |

#### 한줄 요약
- 경고 재현•실행 가능성 검토•배포 판정의 연결 구조이다.


## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **재현 가능한 분석**: 같은 소스•의존성•컴파일 옵션•룰셋으로 다시 실행하여 같은 경고를 얻는 분석이다.
- **증거 기반 판정**: 호출 경로•입력 통제•실행 가능 조건•업무 영향을 근거로 경고 상태를 확정하는 절차이다.
- **위험 수용**: 즉시 수정할 수 없는 실제 위험에 보완 통제•책임자•만료 기한을 지정하고 제한적으로 승인하는 결정이다.
- **정적 경고•오염 흐름 분석**: 경고 지점과 위험 함수까지의 데이터 경로를 산출하는 단계이다.
- **실행 가능성•통제 유효성 검증**: 실제 호출 조건과 입력 검증 및 권한 통제를 확인하는 단계이다.
- **TP•FP•위험 수용 판정**: 경고를 실제 결함•오탐•제한 승인 대상으로 구분하는 단계이다.
- **수정•예외•통과 결정**: 판정 결과에 따라 수정•예외•게이트 통과를 정하는 단계이다.

</details>

```text
분석 도구
   │ 1. 정적 경고•오염 흐름 분석
   ▼
검토자
   │ 2. 실행 가능성•통제 유효성 검증
   ▼
검토자
   │ 3. TP•FP•위험 수용 판정
   ▼
품질 게이트
   │ 4. 수정•예외•통과 결정
```

### 동작 원리

1. **정적 경고•오염 흐름 분석**: **재현 가능한 분석**으로 **심각도**•**신뢰도**와 경로를 산출한다.
2. **실행 가능성•통제 유효성 검증**: **증거 기반 판정**에 필요한 조건을 확인한다.
3. **TP•FP•위험 수용 판정**: **위험 수용** 여부를 포함해 상태를 구분한다.
4. **수정•예외•통과 결정**: 보완 통제와 기한을 기록한다.

#### 한줄 요약
- 도구 경고의 실제 결함 판정과 배포 게이트 연계가 핵심이다.


## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **도구 심각도**: 일반적인 규칙 위험을 기준으로 분석 도구가 부여한 등급이다.
- **업무 위험도**: 실제 배포 환경의 도달 가능성•데이터 가치•영향 범위를 반영하여 조직이 판정한 우선순위이다.
- **TP•FP 적용**: 실제 실행•공격 경로의 성립 여부에 따라 경고를 분류하는 방식이다.
- **수용 대상 위험**: 즉시 수정할 수 없지만 보완 통제로 제한할 수 있는 실제 위험이다.

</details>

정적 분석 경고는 먼저 사실 여부를 분류하고, 실제 위험으로 확인된 항목에 후속 처분을 결정한다. 위험 수용은 참 양성•거짓 양성과 같은 분류 유형이 아니다.

| 판단 단계 | 판정 기준 | 후속 조치 |
|:---|:---|:---|
| 사실 분류 | **TP•FP 적용**에 따른 참 양성 | 수정•재검증 또는 업무 위험 평가 |
| 사실 분류 | **TP•FP 적용**에 따른 거짓 양성 | 근거•만료일을 둔 예외 처리 |
| 처분 결정 | **수용 대상 위험** | 승인•기한•보완 통제를 둔 위험 수용 |

도구가 부여한 **도구 심각도**는 출발점이며, 도달 가능성과 업무 영향을 반영한 **업무 위험도**로 처리 우선순위를 다시 정한다.

> 요약: 경고의 사실 여부를 먼저 분류하고, 확인된 위험은 수정하거나 승인된 통제 아래 제한적으로 수용이 핵심이다.

#### 한줄 요약
- 프로그램 고장 가능성과 공격자 악용 가능성에 따른 경고를 판정한다.


## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **품질 게이트**: 허용 기준을 넘는 미해결 고위험 경고가 있으면 빌드나 배포를 중단하는 통제이다.
- **예외 지시어**: 검토된 오탐을 다음 분석에서 제외하도록 코드나 도구에 남기는 표시이다.
- **예외 만료**: 코드•룰셋•환경 변화 뒤 기존 오탐 판단을 재검토하도록 예외에 유효기간을 두는 정책이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 도구 심각도만 따른 우선순위 왜곡 | **분류 검토** | 실제 위험 중심의 수정 순서 확보 |
| 근거 없는 예외에 따른 취약점 은폐 | **예외 지시어**에 사유•승인자•**예외 만료** 기록 | 잔여 위험 추적 |
| 룰셋•환경 변경에 따른 기준선 단절 | **품질 게이트**에서 환경•룰셋 버전 고정 | 재현성 확보 |

#### 한줄 요약
- 검증 없는 결제 요청의 질의 실행 도달을 참 양성으로 판정하고 매개변수화로 차단이 핵심이다.


## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **경고 수와 위험의 구분**: 많은 저위험•오탐 경고보다 도달 가능한 고영향 경고를 먼저 해결해야 한다는 원칙이다.
- **추적 가능한 예외**: 경고 식별자•판정 근거•승인자•만료일을 기록하여 나중에 재검토할 수 있는 예외이다.
- **조치 결정**: 도달 가능성•오염 흐름•업무 영향이 큰 참 양성은 수정하고 거짓 양성은 예외, 수용 위험은 기한을 두어 승인하는 판단이다.

</details>

- **경고 수와 위험의 구분**에 따라 **추적 가능한 예외**를 관리하고 **조치 결정**을 수행한다.

#### 한줄 요약
- 경고 수보다 실제 입력 도달성과 피해 규모를 우선한 위험을 판정한다.
