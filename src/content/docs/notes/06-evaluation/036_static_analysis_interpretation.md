## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **정적 분석 결과 해석(Static Analysis Result Interpretation)**: 프로그램을 컴파일하거나 실행하지 않은 상태에서 소스 코드나 바이너리를 분석 도구로 스캔하여 검출된 경고(Warning)들에 대해, 실제 런타임 도달 가능성, 데이터 오염 흐름, 비즈니스 피해 파급력을 종합 검토하여 진짜 결함을 솎아내고 조치 우선순위를 판정하는 보안/품질 활동이다.
- **분류 검토(Triage/Review)**: 수천 건씩 쏟아지는 자동화 도구의 경고 목록을 사람이 직접 확인하여, 도구의 오탐(False Positive) 여부를 가려내고 실제 취약점일 경우 배포 차단 및 즉각 수정할지 위험을 수용할지 의사결정하는 핵심 식별 활동이다.
- **오탐(False Positive, FP)**: 정적 분석 도구는 패턴 매칭 기반으로 보수적인 경고를 띄우지만, 개발자가 실제 소스 코드의 실행 문맥(Context)과 별도의 방어 로직(Sanitization 등)을 확인했을 때 런타임 환경에서는 결코 취약점으로 발현되지 않는 가짜 경고 항목이다.

</details>

- 정의/개념: 도달성·오염 흐름·영향으로 **정적 경고**를 판정하는 과정
- 배경/필요성: 경고 수·도구 심각도만으로는 **오탐 구분 불가**

#### 한줄 요약
- 도달성과 피해로 **참 양성·거짓 양성** 판정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **룰셋(Rule Set)**: SQL 인젝션, 크로스 사이트 스크립팅(XSS), 버퍼 오버플로우 등 특정 결함이나 취약점 패턴을 족집게처럼 찾아내기 위해 정적 분석 도구에 탑재해 돌리는 탐지 규칙들의 집합이다.
- **도달 가능성(Reachability)**: 해커가 조작한 악의적인 입력값이 여러 개의 복잡한 함수 호출망과 분기문을 거치더라도, 끊기지 않고 런타임 제어 흐름을 따라 최종 취약점 발생 지점까지 도달할 수 있는 물리적/논리적 가능성이다.
- **오염 흐름(Taint Flow/Data Flow)**: 외부 입력값(Source)이 시스템 내부로 들어와 적절한 정제나 필터링(Sanitization) 없이, 쿼리문 실행이나 시스템 명령어 호출 등 치명적인 피해를 유발하는 위험 함수(Sink)까지 오염된 채로 전달되는 데이터의 흐름이다.
- **재현성(Reproducibility)**: 사람의 손길이 개입하지 않고 완전히 동일한 소스 코드, 라이브러리 의존성, 빌드 환경, 룰셋 버전으로 정적 분석을 다시 수행했을 때 항상 100% 동일한 경고 목록과 결과를 얻을 수 있는 시스템적 성질이다.

</details>

- 룰셋·빌드 환경 고정으로 **재현성** 확보
- **오염 흐름·도달 가능성**으로 런타임 위험 판정
- 분류 검토와 만료형 **예외 승인** 적용

#### 한줄 요약
- **Source-Sink 오염 흐름**과 통제 유효성 검증

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **참 양성(True Positive, TP)**: 도구가 경고한 지점을 분석가가 리뷰한 결과, 실제로 런타임 환경에서 공격받거나 오작동할 여지가 명백히 존재하는 진짜 결함 또는 취약점 판정이다.
- **거짓 양성(False Positive, FP)**: 도구가 문자열이나 패턴만 보고 경고를 띄웠으나, 개발자가 프레임워크 차원의 방어벽(방화벽, 인코딩)이나 실행 문맥을 파악해 보니 공격이 불가능한 가짜(오탐) 판정이다.
- **심각도(Severity)**: 해당 취약점 경고가 실제로 런타임에 발현되어 해킹이나 장애로 이어졌을 때 예상되는 정보 유출, 시스템 파괴 등의 비즈니스 피해 수준을 나타내는 지표(Critical, High, Medium 등)이다.
- **신뢰도(Confidence/Certainty)**: 정적 분석 도구가 해당 코드가 취약점 패턴과 일치한다고 분석 엔진 스스로 얼마나 확신하는지(예: 100% 확실, 60% 추정)를 나타내는 기계적 수치이다.
- **판정 이력(Audit Trail)**: 각 경고 항목에 대해 어떤 개발자가 언제 리뷰했고, 왜 오탐(FP)으로 무시했는지 혹은 왜 고위험(TP)으로 판단해 코드를 고쳤는지 그 근거와 승인 내역을 투명하게 보존한 법적/감사용 기록이다.

</details>

```text
정적 분석 판정 체계
├─ 분석 입력
├─ 정적 분석 엔진
├─ 경고 저장소
├─ 분류 검토
└─ 품질 게이트
```

선의 의미: 분석 경고를 사람의 판정과 배포 게이트로 연결

| 구성요소 | 책임 |
|:---|:---|
| 분석 입력 | 소스·빌드 환경·**룰셋 버전** 고정 |
| 정적 분석 엔진 | 제어·**오염 흐름** 기반 경고 생성 |
| 경고 저장소 | 위치·경로·심각도·**판정 이력** 보관 |
| 분류 검토 | **TP·FP**와 위험 수용 판정 |
| 품질 게이트 | 미해결 고위험 TP의 배포 차단 |

#### 한줄 요약
- TP·FP 판정 후 **고위험 TP 배포 차단**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **재현 가능한 분석(Reproducible Analysis)**: 누가 언제 분석 버튼을 누르든 항상 동일한 소스, 의존성, 컴파일 옵션, 룰셋으로 실행되도록 인프라를 통제하여, 과거와 완전히 똑같은 베이스라인 경고 목록을 얻어내는 기술적 기반 분석이다.
- **증거 기반 판정(Evidence-based Triage)**: 경고를 단순 직감으로 끄는 것이 아니라, 오염 데이터의 소스 함수 호출 경로, 입력값 밸리데이션 로직 존재 유무, 해당 서버망의 방화벽 유무 등을 명확한 근거 문서로 삼아 상태를 확정하는 엄격한 리뷰 절차이다.
- **위험 수용(Risk Acceptance/Waiver)**: 진짜 결함(TP)이 맞고 심각도도 높지만, 시스템을 뜯어고치려면 인프라 교체 등 막대한 비용이 들 경우 WAF(웹 방화벽) 등 보완 통제를 적용한 후 임원진 승인하에 일정 기한까지 예외적으로 안고 가는 경영적 판단이다.
- **정적 경고•오염 흐름 분석**: 분석 엔진이 해커의 입력단부터 DB 쿼리 등 위험 함수에 도달할 때까지의 데이터 이동 경로(Data Flow)를 스캔해 내는 1차 단계이다.
- **실행 가능성•통제 유효성 검증**: 검토자가 소스 코드 문맥을 파악해 해당 분기가 실제로 실행 가능한지, 중간에 방어 로직이 정상 작동하는지 눈으로 검증하는 2차 단계이다.
- **TP•FP•위험 수용 판정**: 검증을 마친 경고들을 당장 뜯어고칠 진짜 결함, 무시할 오탐, 예외적으로 살려둘 위험(Waiver) 세 바구니로 분류하는 3차 단계이다.
- **수정•예외•통과 결정**: 판정 결과에 기반하여 CI 빌드를 끊고 소스를 수정할지, 아니면 예외 처리 후 품질 게이트를 통과시켜 상용 배포를 진행할지 최종 결행하는 마감 단계이다.

</details>

```text
분석 도구
   │ 1. 정적 경고•오염 흐름 분석
   ▼
검토자
   │ 2. 실행 가능성•통제 유효성 검증
   ▼
검토자
   │ 3. TP•FP•위험 수용 판정
   ▼
품질 게이트
   │ 4. 수정•예외•통과 결정
```

### 동작 원리

1. **정적 경고•오염 흐름 분석**: 경고 심각도와 데이터 경로 산출
2. **실행 가능성•통제 유효성 검증**: 도달성과 보호 로직 확인
3. **TP•FP•위험 수용 판정**: 오탐·수정·수용 대상 구분
4. **수정•예외•통과 결정**: 고위험 차단과 만료형 예외 적용

#### 한줄 요약
- 오염 경로를 판정해 **수정·예외·배포** 결정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **도구 심각도(Tool Severity)**: 분석 엔진이 사전에 내장된 일반적인 취약점 패턴 사전을 바탕으로, 실제 시스템 구동 환경과 무관하게 기계적으로 맵핑하여 부여한 디폴트 위험 등급(High, Medium 등)이다.
- **업무 위험도(Business Risk)**: 도구의 획일적 등급을 무시하고, 실제 해당 코드가 배포될 서버망의 중요도, 유출 시 타격을 입는 데이터의 민감성(개인정보 여부) 등을 종합 반영하여 조직이 최종적으로 덧입힌 우선순위 등급이다.
- **TP•FP 적용(TP/FP Classification)**: 코드를 스캔해 도출된 경고가 실제 공격 가능한 치명적 결함인지(참 양성), 겉보기엔 그럴싸하지만 무해한 알람인지(거짓 양성)를 명확한 실행 궤적 검증을 통해 이분법적으로 분류하는 진단 체계이다.
- **수용 대상 위험(Acceptable Risk)**: TP로 판명되어 취약점이 맞으나 당장 소스 코드를 건드리면 치명적 장애가 예상될 때, 웹 방화벽 패턴 차단 등 외곽 보완 통제를 통해 임시로 억제해 둔 실제 위험이다.

</details>

정적 분석 경고는 먼저 사실 여부를 분류하고, 실제 위험으로 확인된 항목에 후속 처분을 결정한다. 위험 수용은 시스템을 못 고쳐서 안고 가는 것이지, 참 양성•거짓 양성과 같은 초기 분류 유형이 아니다.

| 판단 단계 | 판정 기준 | 후속 조치 |
|:---|:---|:---|
| 사실 분류 | 실제 결함 **TP** | 수정·재검증 또는 영향 평가 |
| 사실 분류 | 가짜 경고 **FP** | 오탐 근거와 예외 룰 등록 |
| 처분 결정 | **수용 대상 위험** | 승인·기한·보완 통제 적용 |

**도구 심각도**를 도달성과 피해 기반 업무 위험도로 재평가한다.

> TP·FP를 먼저 판정하고 TP는 수정 또는 **위험 수용**

#### 한줄 요약
- 도달 가능한 **고영향 TP**를 최우선 조치

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **품질 게이트(Quality Gate)**: 데브옵스 CI/CD 파이프라인 상에서, 정적 분석 스캔 결과 허용치를 초과하는 치명적(Critical/High) TP 경고가 남아있을 경우 상용계 배포 프로세스를 시스템적으로 완전히 락다운(Lock-down) 시키는 안전 장치이다.
- **예외 지시어(Suppress/Ignore Directive)**: 개발자가 직접 확인한 명백한 오탐(FP) 코드 상단에 주석이나 어노테이션(예: `@SuppressWarnings`)을 달아, 다음번 정적 분석 스캔부터는 해당 라인의 경고를 띄우지 않도록 툴에 지시하는 매직 키워드이다.
- **예외 만료(Waiver Expiration)**: 소스를 수정하기 곤란하여 승인 하에 덮어둔 취약점이나 오탐 판정이 영원한 면죄부가 되지 않도록, 3개월이나 6개월 뒤 시스템 환경/룰셋 변화를 반영하여 강제로 재검토하게끔 유효기간 타임아웃을 거는 보안 정책이다.

</details>

| 제기된 문제 | 적용 대책 | 기대 효과 |
|:---|:---|:---|
| 환경 없는 **도구 심각도** 맹신 | 전문가 **분류 검토** | 실제 위험에 수정 공수 집중 |
| **예외 지시어** 남용 | 사유·교차 검토·**예외 만료** | 영구 취약점 은폐 방지 |
| 룰셋·환경 변경의 기준선 붕괴 | 분석 환경·엔진 버전 고정 | 분석 **재현성** 확보 |

#### 한줄 요약
- Source-Sink 도달은 TP, 유효한 정제는 **FP 근거**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **경고 수와 위험의 구분(Distinguishing Volume vs Risk)**: 리포트에 찍힌 1만 개의 잡다한 저위험 오탐 경고보다, 해커가 외부망에서 찔러넣어 내부 DB를 털 수 있는 단 1개의 '도달 가능한 고영향' 크리티컬 경고를 0순위로 박멸해야 한다는 절대적 통제 원칙이다.
- **추적 가능한 예외(Traceable Exception/Waiver)**: 개발 편의를 위해 무작정 경고를 꺼버리는 것이 아니라, 고유 경고 식별 번호, 오탐으로 판정한 구체적 코드 궤적 사유, CISO 등 승인권자의 결재 기록, 만료 시한을 데이터베이스에 박아 나중에 감사 시 완벽히 소명할 수 있는 예외 처리 체계이다.
- **조치 결정(Action Decision)**: 도달 궤적이 증명되고 파급력이 큰 결함(TP)은 배포를 막고 소스를 고치고, 방어 코드가 입증된 거짓 양성(FP)은 주석으로 끄며, 건드릴 수 없는 낡은 레거시의 진짜 결함은 유효기간을 걸어 수용(Waiver)하는 최고 등급의 판단 절차이다.

</details>
