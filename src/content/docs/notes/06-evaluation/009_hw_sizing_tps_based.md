## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **HW(Hardware) 규모 산정(Hardware Sizing, 인프라 용량 계획)**: 비즈니스 조직이 합의한 미래 목표 부하량과 데이터 폭증 시나리오를 바탕으로, 이를 감당해 낼 수 있는 최적의 CPU 코어 수, 물리 메모리, 스토리지 입출력 대역폭 등 필수 컴퓨팅 하드웨어 자원 요구 스펙을 수학적으로 정밀 환산 기획하는 아키텍팅 작업.
- **TPS(Transactions Per Second, 초당 시스템 처리 건수)**: 인프라가 1초 동안 어떠한 오류 지연 없이 온전하게 성공 배출 완료해 낸 비즈니스 업무 거래 로직 수로, 시스템 확장 과금 한계를 가늠하는 용량 척도.
- **용량 보정(Capacity Calibration, 여유 마진 튜닝 조율)**: 이론적으로 산출된 단건 거래당 필요 자원 원단위 수치에 머물지 않고, 이벤트 피크타임 쏠림 현상, 연간 누적 성장률 스케일, 하드웨어 이중화 단절 리스크, 그리고 긴급 장애 흡수 여유분 버퍼 조건을 종합적으로 가중 반영하여 실제 투자되어야 할 절대 요구 하드웨어 수량 스펙으로 현실 조정 증폭하는 리스크 헤지(Hedge) 과정.

</details>

- 정의/개념: 목표 **TPS**를 CPU·메모리·I/O로 변환
- 배경/필요성: 평균만으로는 **피크·단일 장애 용량 부족**

#### 한줄 요약

- 거래량·원단위로 **CPU·메모리·I/O 역산**

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **피크 계수(Peak Factor, 순간 집중 할증 배수)**: 하루 전체로 나누어 희석된 허수 평균 부하량에 만족하지 않고, 출퇴근 시간 혹은 예매 폭주 이벤트 타임 등 단시간에 트래픽이 쏠리는 현실 최대 극한 부하치를 방어 인프라 스펙으로 끌어올리기 위해 곱해주는 가중치 펌핑 배수(통상 2배~5배 적용).
- **여유 용량(Headroom Margin, 버퍼 룸)**: 향후 수년간의 예상치 못한 마케팅 대박 비즈니스 성장폭이나 잦은 단기 프로모션 폭증 변동, 백그라운드 배치 작업, 그리고 일시적 노드 장애 상황 충격을 부드럽게 흡수하기 위해 정상 부하 설계 시 미리 예약 선점하여 의도적으로 놀게 놔두는 예비 스펙 자원.
- **N-1 조건(N-1 Availability Rule, 최소 클러스터 단일 장애 방어 요건)**: 활성-활성(Active-Active) 다중 클러스터 노드로 구성된 인프라 자원 풀 중 1대의 핵심 물리 머신 서버가 갑작스레 셧다운 고장으로 이탈하더라도, 남겨진 잔여 활성 노드 인스턴스 자원들만으로 약속된 목표 최대 부하량을 지연 없이 완벽히 방어 처리해 내야만 한다는 엄격한 고가용성 인프라 용량 마진 설계 조건식.
- **단계 검증(Phased Verification, 단계별 상호 크로스체크 프로세스)**: 서류상 수학 수식 계산 엑셀 결과를 맹신하지 않고, 공인된 글로벌 인프라 TPC 벤치마크 표준 통계 자료와 대조한 뒤 최종적으로 도입 대상 어플리케이션을 현장에 올려 부하를 쏟아붓는 실물 BMT 부하 시험 결과값으로 단계별로 증명하며 차례로 허점을 메우는 크로스체크 품질 보증 방식.

</details>

- 평균 부하에 **피크 계수**를 적용해 목표 TPS 산출
- **여유 용량·N-1 조건**으로 성장·장애 흡수
- 산정값과 BMT를 **단계 검증**으로 교차 확인

#### 한줄 요약

- 원단위·피크·성장·**N-1 보정**의 통합 적용

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **자원 원단위(Resource Unit-Cost, 단건 트랜잭션 소모 비용)**: 대상 비즈니스 트랜잭션 단 1건을 결점 없이 온전히 수행하기 위해 하드웨어가 필연적으로 희생 지불해야 하는 중앙처리장치(CPU) 점유 밀리세컨드 시간, 할당해야 할 일시적 메모리 공간 바이트 크기, 쏟아내는 디스크 입출력 빈도와 네트워크 데이터 전송 소모량 원천 스펙.
- **CPU(Central Processing Unit, 중앙처리장치) 용량(CPU Computing Capacity)**: 어플리케이션에 빗발치는 무수한 목표 수량의 동시 거래 트랜잭션 로직을 논리 오류나 데드락 지연 없이 신속하게 연산 방어 돌파해 낼 수 있도록 클러스터 팜에 집적되어야 할 순수 총 코어 연산 엔진 자원.
- **I/O(Input/Output) 용량(I/O Bandwidth Capacity, 입출력 버스 대역폭 능력)**: DB 질의 데이터 디스크 블록 읽기 쓰기 레이턴시 및 쏟아지는 네트워크 소켓 통신 전송 부하 트래픽 패킷 뭉치를 병목 대기열 체증 없이 쾌적하게 뚫고 배출 감당해 낼 수 있는 저장매체 및 전송 버스 인프라 채널 인입출 통로 역량.
- **헤드룸(Headroom, 임계 버퍼 안전 구역)**: 예상치 못한 마케팅 잭팟 성장폭 팽창이나 기습적 이벤트 트래픽 변동 스파이크, 더불어 야간 거대 배치 작업이나 서버 인스턴스 부분 노드 탈락 장애 셧다운 등 악재 충격파를 시스템 멈춤 붕괴 없이 너끈히 스프링처럼 흡수해 내기 위해 정상 운용 평시 시점에서는 의도적으로 할당받지 않고 백지상태로 놀게 비워 남겨 두는 물리 자원 스펙 잉여 여유분 마진율(통상 20~30%).
- **산정 변수(Sizing Mathematical Variables)**: TPS 수학 도출 핵심 구성 기호 인자들로, $TPS_{base}$는 현행 통계 기준 평균 기초 처리량 수치, $TPS_{target}$은 보정 계수 할증을 때려 맞은 최종 방어 설계 목표 처리량 수치, $F_{peak}$는 극단적 이벤트 쏠림 가중치 피크 배수 계수, $g$는 기업 경영 비전 연평균 트래픽 스케일업 성장률, $n$은 하드웨어 감가상각 목표 버티기 적용 보증 수명 연수를 상징.
- **중앙처리장치 산정 변수(CPU Dimensioning Variables)**: $t_{CPU}$는 거래 1건당 CPU 프로세서를 점유 괴롭히는 단위 평균 밀리세컨드 시간 원단위, $U_{target}$은 인프라 CPU가 열폭주 대기열 큐 붕괴 없이 버텨낼 수 있는 안전 목표 임계 이용률 가이드라인 제한치(예: 70%), $CPU_{req}$는 이 모든 난관을 극복하기 위해 물리 장비 서버실 랙에 꽂아 넣어야 할 최종 산출 중앙처리장치 물리 코어 환산 절대 개수 수량치.

</details>

```text
                    [CPU•메모리•I/O 구성]
                    /          |          \
       [업무량•목표 TPS] [거래별 자원 원단위] [피크•성장•이중화 보정]
                    \          |          /
                      [벤치마크•BMT 검증]
```

선의 의미: 업무량·원단위·보정값과 실측 검증의 관계이다.

| 주요 Sizing 구성요소 | 기능적 산출 모델링 책임 및 역할 |
|:---|:---|
| 업무량•목표 TPS | 수명주기의 **산정 변수** 확정 |
| 거래별 자원 원단위 | 거래별 **자원 원단위** 측정 |
| 피크•성장•이중화 보정 | **용량 보정** 계수 반영 |
| CPU•메모리•I/O 구성 | **CPU·I/O·헤드룸** 산출 |
| 벤치마크•BMT 검증 | **단계 검증**으로 산정값 확인 |

- 목표 처리량은 $TPS_{base}F_{peak}(1+g)^n$ 산출
- CPU는 $TPS_{target}t_{CPU}/U_{target}$ 산출
- 메모리·I/O는 세션·작업집합·바이트 원단위 산출

#### 한줄 요약

- 목표 TPS에 **성장·N-1·헤드룸 보정** 적용

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **BMT(Benchmark Test, 상호 비교 벤치마킹 테스트)**: 벤더사 영업 사원의 카탈로그 장밋빛 홍보 스펙 수치를 맹신 기각 배제하고, 발주사가 철저히 통제 셋팅한 완벽히 동일한 부하 스크립트 시나리오 인프라 조건 환경의 링(Ring) 위에서 다수 납품 후보 스펙 장비 서버들을 직접 난타 난전시켜 실제 스레드 연산 처리 성능 퍼포먼스와 타임아웃 붕괴 결함을 살벌하게 상대 평가 비교 우위 도출하는 혹독한 실물 모의 성능 시험 심판대.
- **TPC(Transaction Processing Performance Council, 글로벌 인프라 거래처리 벤치마크 성능 평가 위원회)**: 인프라 하드웨어 제조사 벤더(IBM, HP 등) 및 RDBMS 소프트웨어 솔루션 서버(Oracle 등) 간에 객관적 장비 처리량 성능 계측 잣대를 제공 규격화하기 위해 트랜잭션 쿼리 처리량 측정 규격 및 가이드라인 룰을 엄격 통제 관리 발간하는 국제 최고 권위 공인 심판 비영리 위원회 연합.
- **거래별 자원 원단위 산정(Unit Resource Profiling Phase)**: 레거시 코드 시스템 덤프 로그 프로파일링 툴 트레이싱을 분석 가동하여 특정 트랜잭션 비즈니스 로직 거래 한 건 1회전이 수행 완수될 때마다 서버 내부적으로 어느 정도의 CPU 연산 틱 낭비, 임시 RAM 메모리 점유 누수, 디스크 블록 질의 I/O 패킷 소비량을 갉아먹는지 현미경 레벨로 세밀하게 계측 환산해 내는 가장 선행 기초 뼈대 스텝 단계.
- **피크•성장•N-1 요구량 보정(Resilience Calibrating Phase)**: 계산된 순수 밋밋한 뼈대 기준 인프라 자원 요구량에 마케팅 이벤트 트래픽 폭증 사태 최고조 최대 쏠림 부하 가중치 비율, 향후 수명 주기 내 비즈니스 연평균 누적 스케일 성장률 할증, 그리고 물리 서버 1대 셧다운 기절 고장 이탈 시 남은 노드 무정지 커버 방어 잉여 자원 헤드룸 조건 팩터(Factor)들을 수학 펌핑 계수로 융합하여 뻥튀기 방어 보정 튜닝 씌워주는 리스크 헤지(Hedge) 보강 단계.
- **후보 사양•BMT 구성 설계(Architecture Modeling & BMT Design Phase)**: 수학식으로 펌핑 보정 산출된 묵직한 하드웨어 요구량 스펙 수치를 너끈히 충족 소화할 수 있을 유력한 복수 벤더사의 하드웨어 장비 라인업 모델들을 1차 필터링 채택하여 도입 후보군 리스트를 짜고 혹독한 모의 부하 BMT 랩(Lab) 링 테스트 시나리오 토폴로지 구성을 정밀 작전 기획 설계 세팅하는 채비 단계.
- **TPC 참조•BMT 성능 측정(Global Standard Ref. & BMT Telemetry Execution Phase)**: 글로벌 공인 심판 TPC-C 위원회 발간 카탈로그 표준 벤치마크 결과 지표 수치를 1차 참조 비교 영점(Zeroing) 타겟으로 삼고, 실제 도입 유력 벤더 후보 제품군의 CPU 메모리 랙 하드웨어 장비 실물에 엄청난 시뮬레이션 트래픽 포탄 부하를 인정사정없이 쏟아부어, 홍보물과 달리 실 서버가 뿜어내는 라이브 트랜잭션 처리량(TPS), p99 꼬리 응답 지연 열화 지수, 그리고 장비 내부 스레드 큐 붕괴 한계 포화(Saturation) 병목 상태 결함을 가감 없이 발가벗겨 수치 계측해 내는 실전 스파링 테스트 전투 수행 측정 단계.
- **요구량•측정값 비교•사양 선정(ROI Trade-off & Specification Selection Decision Phase)**: 탁상공론 서류에서 계산된 거시 목표 산정 요구량 스펙 마지노선 잣대와 피투성이 BMT 모의 링 랩(Lab) 현장에서 실측 발가벗겨진 하드웨어 인프라 벤치마크 테스트 성능 한계 결과값 스펙 데이터를 다각적으로 냉정하게 저울질 비교 크로스체크 심사하고 도입 예산(ROI)과 가성비를 저울질하여, 발주 기업의 향후 5년 무정지 시스템 운명을 책임질 최종 납품 계약 승자 인프라 자원 구성 사양 솔루션을 최종 도장 찍어 결재 결정 픽스하는 전략적 피날레 마무리 단계.

</details>

```text
업무 책임자
   │ 업무량•목표 TPS 전달
   ▼
```

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **CPU 기반 산정(CPU-centric Processing Unit Sizing, 트랜잭션 연산 코어 자원 용량 계획 수립 기법)**: 트랜잭션 1건이 거치는 복잡다단한 비즈니스 서비스 로직 알고리즘 연산 처리 낭비 틱량과 단일 장애 노드 이탈에도 뻗어버리지 않게 지켜야 할 목표 클러스터 프로세스 코어 활용 이용률 임계 방어선 한계 컷(예: 75% 캡 제한) 수치를 수학 공식으로 교차 믹스하여 전체 데이터센터 랙 팜에 밀어 넣어야 할 궁극적인 물리 실리콘 멀티 프로세서 처리기 코어 머리통 개수 용량을 산술적으로 역계산 도출해 내는 인프라 두뇌 스펙팅 결정 방식.
- **메모리 기반 산정(Memory-centric Footprint Sizing, 세션 버퍼 휘발성 자원 용량 계획 수립 기법)**: 피크 타임 시 시스템에 몰려들어 진을 치고 눌러앉을 막대한 동시 유지 접속 유효 커넥션 세션 객체 총수량 한계치, 멀티 스레드가 펑펑 쏟아내고 수거될 임시 힙(Heap) 객체 워킹 작업 캐시 메모리 집합 덩치, 그리고 DB 풀 등 백그라운드 캐시 시스템 스페이스 램 점유량을 바이트 단위로 합산 추산하여 서버 메인보드 뱅크 슬롯에 꽂아 넣어야 할 필수 물리 RAM 메모리 적재 용량 스펙 기가바이트(GB) 사이즈를 정밀 산술 계산하여 아웃오브메모리(OOM) 뻗음 사태를 차단 방어 도출해 내는 버퍼 인프라 스펙팅 결정 방식.
- **I/O 기반 산정(Input/Output-centric Bandwidth Sizing, 통신 입출력 버스 자원 용량 계획 수립 기법)**: 하나의 비즈니스 거래가 데이터베이스 저장소 매체에 크래시를 남기는 무거운 디스크 블록 I/O 읽기/쓰기 커밋 저장 쓰기 덤프 트래픽 스루풋 빈도 건수와, 외부 서드파티 통신 연동 구간 네트워크 소켓 파이프라인 구간으로 오가는 인/아웃(In/Out) 페이로드 패킷 스트림 전송 바이트 메가 대역폭 데이터량을 정밀 합산하여, SAN/NAS 스토리지 컨트롤러나 10G/40G 스위치 백본 섀시가 포트 버퍼 병목 타임아웃 지연 뻗음 현상 없이 쾌속으로 데이터 송수신을 감당 입출력 덤프 처리해 낼 수 있는 광케이블 통신 전송 버스 대역폭 용량 한계 스펙을 계산 역추산 인프라 스펙팅 방어망 구축 도출 방식.

</details>

| 인프라 하드웨어 도입 산정 기준 관점 축 | 핵심 튜닝 입력 원단위 프로파일 지표 | 치명적 결함 방지 필수 보정 여유 마진 항목 지표 |
|:---|:---|:---|
| CPU 연산 자원 | **CPU 기반 산정**의 거래당 CPU 시간 | 목표 이용률·N-1 헤드룸 |
| RAM 메모리 자원 | **메모리 기반 산정**의 세션·작업집합 | GC 지연·누수·피크 세션 |
| 디스크·네트워크 자원 | **I/O 기반 산정**의 거래당 바이트 | 대역폭·큐·꼬리 지연 |

> 요약: 성능 붕괴의 3대 주범 영역인 논리 연산 병목 방어를 위한 **CPU 기반 산정** 기법과, 버퍼 고갈 OOM(Out of Memory) 셧다운 차단을 위한 **메모리 기반 산정** 기법, 마지막으로 스토리지 디스크 및 10G 네트워크 병목 통신 딜레이 폭주 압박 방어를 위한 **I/O 기반 산정** 기법 채널 축을 상호 삼각 분리 구획하여 각 물리 매체 인프라 특성에 걸맞게 각각의 전용 독립 특화 스케일업 파괴 방어 복원 마진 보정 지표 계수 공식을 믹스 매치 세팅 곱셈 조율해 튜닝 적용 산출하는 고차원 복합 하드웨어 무정지 방어 인프라 스펙팅 설계 전략 모델링 아키텍처.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **tpmC(Transactions per Minute C, TPC-C 벤치마크 기반 도매 주문 업무 1분당 트랜잭션 갱신 완료 처리 계측 횟수 단위 수치)**: TPC-C 글로벌 공인 벤치마크 시나리오 잣대에 기반하여, 복잡한 인서트/업데이트 로직이 얽혀있는 가상의 악덕 도매 물류 창고 공급업체 신규 접수 주문 트랜잭션 로직을 서버 인프라 장비가 60초(1분) 동안 데드락이나 DB 타임아웃 붕괴 오류 없이 완벽 무결하게 인서트 커밋 성공 완료 배출해 낸 합계 횟수 누적 카운트 수치로 벤더사 인프라 홍보 스펙 기준의 바이블.
- **TPC-C(Transaction Processing Performance Council-C, 복합 DB 갱신 갱신 중심 도매 물류 주문 트랜잭션 벤치마킹 표준 모델)**: TPC 국제 위원회가 벤더 장비의 기초 체력 한계를 까발리기 위해 극악하게 설계 제정한 낡고 무거운 고전적 성능 검증 테스트 잣대로, 인프라 장비에 수백 개의 물류 창고 스레드가 미친 듯이 달라붙어 무거운 다중 테이블 조인 및 레코드 데이터 삽입 갱신 락(Lock) 충돌 병합 주문 트랜잭션을 마구 쏟아붓는 가장 가혹한 복잡 도매 공급 창고 비즈니스 모사형 원조 벤치마크 시나리오 시뮬레이션 모델 룰.
- **TPC-E(Transaction Processing Performance Council-E, 최신형 금융권 증권사 멀티 읽기 주도 초단타 트랜잭션 벤치마킹 진화 모델)**: 레거시 TPC-C의 낡은 잣대 한계 맹점을 극복 대체하고자 TPC 위원회가 새롭게 론칭한 차세대 성능 검증 잣대로, 현대 엔터프라이즈 환경에 완벽 부합하도록 최신 고도화된 증권사 초단타 매매 주식 거래 시스템의 복잡기괴한 캐싱 쿼리 로직, 방대한 리드(Read) 위주 탐색 연산, 그리고 미세 비동기 데이터베이스 I/O 얽힘 동시성 접근 비즈니스 패턴을 현미경처럼 아주 정밀하게 묘사하여 장비의 인프라 병목 숨통을 조여보는 최신 트렌드형 벤치마크 모의 실험 모사 스펙팅 기준 룰.
- **99백분위수(p99, 99th Percentile Tail Latency, 상위 1% 악성 꼬리 응답 지연 경계선 컷오프 지표)**: 벤치마킹 테스트 시 수십만 건의 난타 트래픽 응답 소요 시간 결과값들을 단조로운 뭉뚱그림 평균 함정 은폐 왜곡에서 구출하기 위해 도입한 차갑고 냉정한 통계학적 검수 잣대 수치로, 전체 응답 트랜잭션 덤프를 속도 순으로 1등부터 줄 세워 나열 정렬했을 때 하위 99% 무더기 요청 건수들이 모두 통과 커트라인 기준선 이하에서 안도하며 완료 렌더링 떨어지는 극한 지점의 마지노선 타임 리미트 값을 지칭하며, 극악무도하게 튀는 소수 1%의 느림보 꼬리 지연 악성 랙(Lag) 타임아웃 체감 사용자 컴플레인 현상을 현미경처럼 잡아내 척결하는 품질 튜닝 방어의 가장 깐깐한 대표 지표 마지노선 지수.

</details>

|:---|:---|:---|
| TPS와 tpmC 단위 혼동 | **tpmC**를 초 단위로 환산 | 60배 환산 오류 방지 |
| 벤치마크와 업무 특성 괴리 | **TPC-C·TPC-E** 교차 참조 | 업무 적합성 보완 |

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **OLTP(Online Transaction Processing, 온라인 찰나 실시간 분산 거래 쿼리 동시 다발 처리 아키텍처 방식)**: 거대한 분석 배치 작업과 대조적으로, 수천수만의 유저가 동시다발적으로 로그인, 장바구니 담기, 간편 결제 승인 클릭 등 아주 짧고 빈번하게 발생하는 파편화된 소규모 DB CRUD(생성/조회/수정/삭제) 거래 트랜잭션 패킷들을 지연 타임아웃 없이 눈 깜짝할 찰나에 잽싸게 응답 완료 처리 반환하는 현대 IT 웹 모바일 시스템 인프라 뼈대의 가장 핵심적인 구동 통신 방식 모델.
- **실측 검증(Empirical Physical BMT Verification, 랩 현장 실물 링 모의 난타 확인 교차 입증 사살 절차)**: 책상머리 서류 엑셀 시트 엑셀 수식 계산만으로 그럴싸하게 통과 채점 골라낸 서류 전형 통과 하드웨어 인프라 벤더 랙 장비 후보 사양이, 발주사가 요구한 악독한 목표 타겟 트래픽 빗발 TPS, 악성 1% 소외 타임아웃 유저 꼬리 지연 p99 허용 임계 커트라인 마지노선, 그리고 CPU/메모리 하드웨어 과열 한계 돌파 OOM 뻗음 차단 버티기 능력 조건 가이드라인을 정말 라이브 현장에서도 무적처럼 흔들림 없이 만족 방어해 내는지, 가혹한 실물 링 BMT 스트레스 랩 모의 난타 폭격 부하 시험 시뮬레이터로 피투성이 까발려 직접 두들겨 패 확인 증명 도장을 찍는 최종 서바이벌 인프라 확인 스파링 스펙팅 인증 검수 절차 프로세스.
- **사양 채택(Specification Sign-off Final Decision, 인프라 장비 랙 납품 벤더 스펙 최후 승인 결재 체결 결정)**: 단건 쿼리 자원 코스트 원단위 역추산 공식, 피크타임 마케팅 트래픽 쏠림 폭주 펌핑 가중치 방어막, 그리고 치명적 단일 서버 노드 셧다운 기절 장애 대비용 N-1 클러스터 잉여 버퍼 마진 헤드룸 조건 룰을 삼단 콤보로 적용하여 유력 서류 납품 장비 인프라 후보를 조심스레 리스트업 산정한 뒤, 다시금 잔혹한 랩 링에서의 벤치마크 쏟아붓기 극한 목표 처리량 빗발 테스트 트래픽 폭격 방어전과 악성 1% 소외 유저 꼬리 지연(p99) 무결점 커트라인 통과 스파링 시험 검증 난타전을 뻗지 않고 모두 무사히 살아남아 생존 통과 증명한 최고 ROI 가성비 독보적 무정지 방어 구성 챔피언 벤더 솔루션만을 발주사 차세대 인프라 데이터센터 랙의 최종 주인으로 간택 낙점 선택해 천문학적 예산 결재 서류에 최종 사인 서명 날인하는 아키텍트의 최고 권위 심사 전략적 최후 결단 판정 의사 결정 액션.

</details>
