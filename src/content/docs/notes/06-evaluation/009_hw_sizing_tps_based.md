## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하드웨어 규모 산정(Hardware Sizing)**: 목표 처리량과 요구사항을 기반으로 필요한 CPU, 메모리, 디스크 I/O 용량을 산출하는 설계 작업.
- **초당 트랜잭션 수(Transactions Per Second, TPS)**: 1초 동안 성공적으로 완료 처리하는 비즈니스 트랜잭션 건수.
- **용량 보정(Capacity Calibration)**: 피크 집중률, 연간 데이터 증가율, 고가용성 마진을 적용해 최종 필요 사양을 결정하는 절차.

</details>

- 정의/개념: 목표 TPS와 트랜잭션당 자원 원단위를 기반으로 CPU·메모리·I/O 하드웨어 용량을 산출하는 설계 기법
- 배경/필요성: 단순 평균 처리량만 반영 시 **피크 부하 및 단일 노드 장애 시 용량 부족** 발생

#### 한줄 요약

- 거래량과 원단위를 분석하여 **CPU·메모리·I/O 자원 용량 역산** ## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **피크 계수(Peak Factor)**: 일평균 처리량 대비 트래픽 집중 시간대의 최대 부하를 반영하기 위해 적용하는 배수 계수.
- **여유 용량(Headroom)**: 단기 트래픽 변동, 배치 작업 및 일시적 노드 장애를 완충하기 위해 사전 확보하는 버퍼 자원.
- **N-1 가용성 요건(N-1 Availability Rule)**: 다중 노드 클러스터 중 1대 장애 발생 시에도 잔여 노드만으로 전체 목표 트래픽을 처리할 수 있는 설계 조건.
- **단계 검증(Phased Verification)**: 이론 공식 계산, TPC 표준 벤치마크 참조, 실물 BMT 테스트를 순차적으로 거치며 산정치를 확정하는 검증 방식.

</details>

- 평균 부하에 **피크 계수** 활용 적용해 목표 TPS 산출
- **여유 용량과 N-1 요건** 기반 비즈니스 성장 및 노드 장애 수용
- 산정값과 벤치마크 결과를 **단계 검증** 기반 상호 교차 확인

#### 한줄 요약

- 원단위 분석과 피크·성장률·**N-1 보정** 통합 적용

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자원 원단위(Resource Unit Cost)**: 단일 트랜잭션 1건을 처리하는 데 소요되는 CPU 시간(ms), 메모리 점유량(Byte), 디스크 I/O 횟수.
- **목표 이용률(Target Utilization, U)**: 자원 병목과 지연 급증을 방지하기 위해 설정하는 최대 허용 자원 사용률 한계(통상 70%).
- **산정 매개변수(Sizing Parameters)**: 기준 처리량($TPS_{base}$), 피크 계수($F_{peak}$), 연간 성장률($g$), 내구 연수($n$) 등 용량 산출에 쓰이는 핵심 변수.

</details>

```text
하드웨어 규모 산정 아키텍처
├─ 입력부: 업무량 및 목표 TPS / 거래별 자원 원단위
├─ 보정부: 피크 계수 / 연간 성장률 / N-1 이중화 보정
├─ 산출부: CPU 코어 수 / 메모리 용량 / I/O 대역폭
└─ 검증부: 공인 TPC 벤치마크 참조 및 실물 BMT 검증
```

선의 의미: 업무 요구량과 자원 원단위에 보정 계수를 적용하여 하드웨어 스펙을 산출하고 BMT로 검증하는 구조.

| 구성요소 | 책임 |
|:---|:---|
| 업무량 및 목표 TPS | 수명주기 내 기준 트랜잭션 처리량과 **산정 매개변수** 확정 |
| 거래별 자원 원단위 | 트랜잭션당 소요되는 **자원 원단위(CPU·메모리·I/O)** 프로파일링 |
| 용량 보정 계수 | 피크 집중률, 연간 성장률, **N-1 가용성 요건** 반영 |
| 자원 사양 산출 | 목표 이용률을 반영한 **CPU 코어·메모리·I/O 용량** 결정 |
| 벤치마크 검증 | 표준 TPC 참조치 및 실물 **BMT 단계 검증** 수행 |

#### 한줄 요약

- 목표 TPS에 **성장률·N-1·헤드룸 보정** 적용하여 세부 자원 산출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **벤치마크 테스트(Benchmark Test, BMT)**: 동일한 시험 환경에서 다수 벤더 장비의 실제 처리량과 응답시간을 비교 측정하는 성능 시험.
- **거래처리 성능위원회(Transaction Processing Performance Council, TPC)**: 하드웨어 및 DB 처리 성능을 공정하게 평가하기 위해 표준 벤치마크 규격을 제정하는 비영리 단체.
- **자원 원단위 측정(Unit Resource Profiling)**: 프로파일러를 통해 트랜잭션 1건당 CPU 시간, 메모리 사용량, I/O 빈도를 측정하는 단계.
- **사양 선정(Specification Selection)**: 산정 요구량과 실측 BMT 성능을 종합 평가하여 최종 도입 하드웨어 규격을 확정하는 절차.

</details>

```text
업무 책임자
   │ 업무량·목표 TPS 전달
   ▼
산정 분석기
   │ 1. 거래별 자원 원단위 산정
   │ 2. 피크·성장·N-1 요구량 보정
   ▼
공급자 제안
   │ 3. 후보 사양·BMT 구성 설계
   ▼
BMT 환경
   │ 4. TPC 참조·BMT 성능 측정
   ▼
사양 선정자
   │ 5. 요구량·측정값 비교·사양 선정
   ▼
권고 자원 사양 확정
```

**동작 원리** 1. **거래별 자원 원단위 산정**: 프로파일링을 통한 트랜잭션당 CPU·메모리·I/O 소요량 계측
2. **피크·성장·N-1 요구량 보정**: 피크 계수, 미래 성장률, 단일 노드 장애 헤드룸 반영
3. **후보 사양·BMT 구성 설계**: 산정치를 충족하는 벤더 후보군 구성 및 시험 시나리오 수립
4. **TPC 참조·BMT 성능 측정**: TPC 표준 참조치와 실물 BMT 부하 시험을 통한 TPS·p99 지연 측정
5. **요구량·측정값 비교·사양 선정**: 도입 비용과 성능 실측치를 비교하여 최적 장비 사양 확정

#### 한줄 요약

- 원단위 산정 후 **피크·성장·N-1 실측 검증** 거쳐 장비 선정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CPU 기반 산정(CPU-centric Sizing)**: 트랜잭션당 소요 CPU 시간과 목표 이용률 한계를 기준으로 필요 물리 코어 수를 도출하는 방식.
- **메모리 기반 산정(Memory-centric Sizing)**: 피크 동시 세션 수, 작업 힙 메모리, OS 및 DB 버퍼 캐시 크기를 합산하여 필요 RAM을 도출하는 방식.
- **I/O 기반 산정(I/O-centric Sizing)**: 트랜잭션당 디스크 블록 읽기/쓰기 횟수와 네트워크 전송량을 합산하여 스토리지 IOPS 및 대역폭을 산정하는 방식.

</details>

| 자원 유형 | CPU 연산 자원 | RAM 메모리 자원 | 디스크·네트워크 자원 |
|:---|:---|:---|:---|
| 적용 기준 | 비즈니스 연산 병목 방어 | 동시 접속 세션 및 캐시 유지 | 스토리지 IOPS 및 대역폭 확보 |
| 핵심 입력 원단위 | 거래당 소요 CPU 시간($t_{CPU}$) | 세션당 메모리 및 작업 힙 크기 | 트랜잭션당 블록 크기 및 전송량 |
| 한계 | 코어 증설 한계 및 순차 병목 | GC 오버헤드 및 누수 위험 | 스토리지 큐 지연 및 병목 발생 |

> 요약: CPU 연산, 메모리 버퍼, 스토리지 I/O 자원 축을 분리하여 각각의 고유 원단위와 보정 계수를 적용 산출.

#### 한줄 요약

- CPU·메모리·I/O별 **독립 원단위·헤드룸 산정** 기반 자원 불균형 방지

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **tpmC(Transactions Per Minute C)**: TPC-C 벤치마크 기준 분당 처리된 신규 주문 트랜잭션 완료 건수.
- **TPC-C / TPC-E**: 복합 데이터베이스 갱신 중심(TPC-C) 및 증권·금융 읽기 중심(TPC-E)의 공인 OLTP 성능 벤치마크 표준 모델.
- **99백분위수 지연시간(99th Percentile Latency, p99)**: 전체 요청 중 상위 99%가 완료되는 응답 지연 경계값으로 꼬리 지연 측정 지표.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| TPS와 tpmC 단위 혼동으로 인한 용량 오산 | **tpmC** 활용 초당 처리량(TPS)으로 정밀 환산 | 60배 규모 산정 오류 차단 |
| 표준 벤치마크와 실제 업무 특성 간 괴리 | 업무 형태에 따라 **TPC-C 및 TPC-E** 교차 참조 | 워크로드 적합성 보완 |
| 미래 성장 및 노드 장애 시 용량 부족 | 연평균 성장률과 **N-1 헤드룸** 필수 반영 | 피크 트래픽 및 단일 장애 흡수 |
| 카탈로그 수치와 실제 성능 간 차이 | 도입 후보 장비 대상 실제 업무 기반 BMT 수행 | **p99 지연 및 포화 임계점 실측** |

#### 한줄 요약

- 도입 전 실제 업무 시나리오 기반 **BMT로 TPS와 p99 지연 검증** ## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **온라인 트랜잭션 처리(Online Transaction Processing, OLTP)**: 다수의 사용자가 발생하는 단건 트랜잭션을 실시간으로 처리하는 시스템 환경.

</details>

- OLTP 원단위와 N-1 조건 기반 용량 산정 후 **실물 BMT 검증을 통한 최종 사양 확정** #### 한줄 요약

- 이론 산정값과 BMT 실측치를 교차 비교하여 **비용·성능 최적 사양 확정**
