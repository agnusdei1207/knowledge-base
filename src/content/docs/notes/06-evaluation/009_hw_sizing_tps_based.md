## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하드웨어 규모 산정(Hardware Sizing / Capacity Planning / TTA & 행정안전부 지침)**: 공공 및 금융, 기업 정보시스템 구축 시 목표 비즈니스 트랜잭션 처리량(TPS)과 업무별 자원 원단위(Unit Cost)를 기반으로, 피크 집중률($F_{peak}$), 시스템 목표 이용률($U_{target}$), 연간 데이터 증가율($g$), N-1 고가용성 마진을 수리적으로 반영하여 최적의 CPU 코어 수(tpmC), 메모리 용량(GB), 스토리지 IOPS를 정밀 산출하는 표준 엔지니어링 프로세스.
- **주관적 추정에 따른 과잉 투자 및 피크 용량 부족 결함(Under/Over-sizing Defect)**: 과학적 산정 기준 없이 공급업체(Vendor)의 권고나 단순 일평균 처리량만을 적용하여, 수십억 원의 하드웨어 예산을 낭비하거나 오픈 당일 피크 트래픽 집중 및 단일 서버 장애(N-1) 발생 시 시스템 전체가 다운되는 구조적 결함.

</details>

- 정의/개념: 시스템 도입의 경제성과 고가용성을 동시에 보증하기 위해 **기준 TPS 및 자원 원단위 프로파일링 $\rightarrow$ 피크 계수($F_{peak}$) 및 연간 성장률($g$) 보정 $\rightarrow$ TTA 표준 공식 기반 CPU/메모리/디스크 산출 $\rightarrow$ TPC 벤치마크(TPC-C/tpmC) 환산 $\rightarrow$ 실물 BMT(벤치마크 테스트) 교차 검증** 을 집행하는 **표준화된 용량 산정 체계**
- 배경/필요성: 정보화 사업의 예산 낭비를 방지하고 객관적 근거에 기반한 인프라 도입을 법적으로 강제하기 위해 행정안전부 및 TTA(한국정보통신기술협회) 표준 가이드라인 준수 필수화

#### 한줄 요약
- 하드웨어 규모 산정은 TTA 표준 지침에 따라 목표 TPS에 피크율, 목표 가동률, N-1 보정을 적용하여 최적 스펙을 도출한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **규모 산정 4대 핵심 보정 파라미터**:
  - **피크 집중 계수 ($F_{peak}$, Peak Factor)**: 일평균 트래픽 대비 최대 피크 시간대(1시간)의 부하 집중 배수 (보통 2.0 ~ 4.0).
  - **목표 시스템 이용률 ($U_{target}$, Target Utilization)**: 대기열 급증을 방지하기 위한 최대 허용 CPU 사용률 한계 (일반적으로 70% 이하).
  - **연간 성장률 ($g$, Annual Growth Rate)**: 시스템 내용연수($n$년, 보통 3~5년) 동안의 비즈니스 트래픽 연평균 증가율.
  - **N-1 이중화 보정 계수 (N-1 Redundancy Margin)**: 클러스터 내 1대 노드 장애 시에도 잔여 노드만으로 100% 피크 부하를 수용할 수 있는 가용성 마진.

</details>

- **표준화된 수리 산정 공식(TTA Sizing Standard)**: 행안부 고시 기준에 따라 OLTP, WEB/WAS, 배치(Batch) 서버 유형별로 정형화된 수학적 공식 제공
- **자원 축별 독립 산정 및 상호보완**: CPU 연산(코어/tpmC), 메모리 세션/버퍼(RAM), 스토리지 처리량(IOPS/용량)을 독립 계산하여 자원 불균형(Imbalance) 방지
- **이론값과 실측치의 단계적 교차 검증**: 이론 공식 산출치 $\rightarrow$ TPC 공인 벤치마크 참조 $\rightarrow$ 실물 BMT 테스트를 순차 적용하는 3단계 정합성 검증

#### 한줄 요약
- TTA 표준 공식 적용, 4대 보정 계수 반영, CPU/메모리/I/O 독립 산출, BMT 3단계 교차 검증을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TPS 기반 OLTP CPU 규모 산정 표준 공식 (행안부/TTA 지침)**:
  - $\text{Required Peak TPS} = TPS_{base} \times F_{peak} \times (1 + g)^n$.
  - $\text{Required CPU Cores} = \frac{\text{Required Peak TPS} \times t_{cpu}}{U_{target} \times (1 - \text{N-1 Penalty})}$.
  - $\text{Required tpmC} = \text{Required Peak TPS} \times 60 \times \text{Complexity Multiplier}$.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 비즈니스 요구사항 및 원단위 입력 계층 (Input Layer) ]             │
│  ├─ 기준 트랜잭션: $TPS_{base} = 1,000 \text{ req/sec}$                  │
│  └─ 트랜잭션당 소요 CPU 시간: $t_{cpu} = 10\text{ms} = 0.01\text{초}$   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (4대 보정 계수 적용)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 용량 보정 계수 파이프라인 (Capacity Calibration Engine) ]          │
│  ├─ 1. 피크 계수 ($F_{peak} = 2.0$) ➔ 피크 시 2,000 TPS 유입             │
│  ├─ 2. 연간 성장률 ($g = 20\%, n = 3\text{년}$) ➔ $(1+0.2)^3 = 1.728$    │
│  ├─ 3. 목표 가동률 ($U_{target} = 0.70$) ➔ 70% 임계치 설정               │
│  └─ 4. N-1 고가용성 보정 (2대 액티브-액티브 클러스터 기준)               │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (TTA 표준 공식 계산)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 하드웨어 스펙 최종 산출 계층 (Output Sizing Specs) ]               │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ CPU 코어 및 tpmC ]              │ [ 메모리 (RAM) 및 스토리지 (Disk) ] │
│ ├─ 목표 피크 TPS: 3,456 TPS       │ ├─ 세션 메모리 + DB 버퍼 풀: 512GB  │
│ ├─ 필요 순수 코어: 50 Cores       │ ├─ 연간 데이터 누적: 20TB           │
│ └─ tpmC 환산: 1,036,800 tpmC      │ └─ 스토리지 IOPS: 50,000 IOPS 확보  │
└───────────────────────────────────┴─────────────────────────────────────┘
```

선의 의미: 입력된 기준 처리량과 원단위에 피크, 성장률, 가동률 보정을 거쳐 최종 CPU, 메모리, 스토리지 스펙을 도출하는 구조

| 산출 영역 | 핵심 계산 공식 | 주요 입력 변수 | 비고 |
|:---|:---|:---|:---|
| **목표 피크 TPS** | $TPS_{peak} = TPS_{base} \times F_{peak} \times (1 + g)^n$ | 기준 TPS, 피크율, 성장률, 연수 | 피크 용량 정의 |
| **CPU 코어 수** | $\text{Cores} = \frac{TPS_{peak} \times t_{cpu}}{U_{target}}$ | $t_{cpu}$ (건당 CPU 소요시간, 초), 가동률 | 물리 코어 산정 |
| **tpmC 환산치** | $\text{tpmC} = TPS_{peak} \times 60 \times C_{weight}$ | $C_{weight}$ (업무 복잡도 계수: 단순3, 복합5)| 공인 벤치마크 비교 |
| **메모리 (RAM)** | $\text{Memory} = \text{OS} + (N_{session} \times M_{session}) + M_{buffer}$| 동시 세션 수, 세션당 메모리, DB 캐시 | OOM 및 스왑 방지 |
| **스토리지 (Disk)**| $\text{Disk} = \text{Data}_{base} \times (1 + g)^n \times (1 + R_{raid})$ | 초기 데이터량, RAID 패리티 마진 | 용량 및 IOPS 확보 |

#### 한줄 요약
- 피크 TPS($TPS \cdot F_{peak} \cdot (1+g)^n$), CPU 코어($\frac{TPS \cdot t_{cpu}}{U_{target}}$), tpmC, 메모리, 스토리지 공식으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TTA 지침 기반 하드웨어 규모 산정 5단계 프로세스**:
  1. 비즈니스 업무 분석을 통해 기본 TPS 및 트랜잭션당 CPU 시간 실측
  2. 피크 집중 계수(2.0) 및 3개년 데이터 성장률(연 20%) 반영
  3. TTA 표준 공식에 따라 목표 피크 TPS 및 필요 CPU 코어 수 계산
  4. TPC-C 벤치마크를 기반으로 tpmC 환산치 도출 및 벤더 제안 사양 비교
  5. 실물 BMT 환경에서 실제 업무 부하를 주입하여 산정된 사양의 적합성 최종 검증

</details>

```text
1. [기본 업무량 및 원단위 측정]
    ├─ 업무 특성: 온라인 증권 거래 시스템 (OLTP 복합 트랜잭션)
    ├─ 평시 기준 처리량: $TPS_{base} = 1,000 \text{ req/sec}$
    └─ [단일 트랜잭션 처리 시 순수 CPU 연산 시간: $t_{cpu} = 10\text{ms} = 0.01\text{초}$]
            │
            ▼
2. [보정 파라미터 확정]
    ├─ 장 시작 피크 집중 계수: $F_{peak} = 2.0$
    ├─ 3개년 연간 트랜잭션 성장률: $g = 20\%$ ($n = 3\text{년} \rightarrow (1+0.2)^3 = 1.728$)
    ├─ 시스템 목표 CPU 가동률: $U_{target} = 0.70$ (70% 한계치 설정)
    └─ [업무 복잡도 가중치: $C_{weight} = 5.0$ (복합 금융 거래)]
            │
            ▼
3. [피크 TPS 및 필요 CPU 코어 산출]
    ├─ 3년 차 목표 피크 TPS: $TPS_{peak} = 1,000 \times 2.0 \times 1.728 = 3,456 \text{ TPS}$
    ├─ 1초당 총 필요 연산 시간: $3,456 \times 0.01\text{초} = 34.56 \text{ CPU-seconds}$
    ├─ 목표 가동률 70% 반영 필요 코어: $\text{Cores} = \frac{34.56}{0.70} = 49.37 \rightarrow 50 \text{ Cores}$
    └─ [N-1 이중화(2대 클러스터) 적용: 서버당 50코어 × 2대 = 총 100 Cores 도출]
            │
            ▼
4. [tpmC 환산 및 장비 스펙 매핑]
    ├─ $\text{Required tpmC} = 3,456 \times 60 \times 5.0 = 1,036,800 \text{ tpmC}$
    └─ [TPC 공인 사이트에서 100만 tpmC 이상을 충족하는 서버 모델(Xeon 64코어 등) 후보군 선정]
            │
            ▼
5. [실물 BMT 부하 검증]
    ├─ 후보 서버에 3,456 TPS 부하 주입 ➔ CPU 가동률 68%, p99 지연 80ms 기록
    └─ [산정치와 실측치 오차 3% 이내 확인 ➔ 최종 하드웨어 발주 확정]
```

**동작 원리**

1. **대기열 급증 방어**: 목표 가동률을 $U_{target} \le 70\%$로 제한하여 큐잉 이론상의 비선형 대기 폭증 구간(하키스틱) 회피
2. **복리 성장 모델 반영**: 연간 성장률 $(1+g)^n$을 복리 적용하여 시스템 구축 후 3~5년 동안 하드웨어 재구매 없는 TCO 최적화
3. **N-1 무중단 보증**: 2대 액티브-액티브 구성 시 1대가 불의의 장애로 셧다운되어도 잔여 1대가 50코어로 70% 가동률 내에서 피크 부하를 100% 정상 수용
4. **tpmC의 표준 척도 활용**: 서버 벤더마다 코어당 IPC(Instruction Per Cycle) 성능이 다른 문제를 TPC 공인 벤치마크(tpmC) 수치로 정규화하여 공정 비교
5. **실측 기반 신뢰성**: 이론 산정치에만 의존하지 않고 BMT를 통해 실제 DB 락 경합 및 I/O 병목을 최종 확인

#### 한줄 요약
- 원단위 측정, 보정 파라미터 확정, 피크 TPS/코어 계산, tpmC 환산, 실물 BMT 검증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **서버 유형별 규모 산정 3대 표준 공식 비교 (TTA 가이드라인)**:
  - OLTP 서버: TPS 및 tpmC 기반 (복합 DB 트랜잭션 중심).
  - WEB / WAS 서버: 동시 사용자 및 페이지뷰(PV) 기반 (네트워크 및 세션 메모리 중심).
  - Batch 서버: 처리 대상 데이터 건수 및 배치 윈도우 시간 기반 (CPU/디스크 집중).

</details>

| 비교 항목 | OLTP 데이터베이스 서버 | WEB / WAS 애플리케이션 서버 | 배치 (Batch) 처리 서버 |
|:---|:---|:---|:---|
| **핵심 산정 기준** | **목표 TPS, tpmC, DB Buffer Cache**| **동시 접속자($N$), 초당 히트수(Hits/sec)**| **총 레코드 건수, 배치 허용 시간(Window)**|
| **주요 산출 공식** | $\text{Cores} = \frac{TPS_{peak} \times t_{cpu}}{U_{target}}$ | $\text{Cores} = \frac{\text{Hits/sec} \times t_{process}}{U_{target}}$| $\text{Cores} = \frac{\text{Total Records} \times t_{record}}{\text{Batch Window (sec)}}$ |
| **주요 제약 자원** | **Disk IOPS, DB Lock, 공유 메모리**| **JVM Heap, 소켓 커넥션, 네트워크 IO**| **CPU 연산 집중, 순차 디스크 I/O 대역폭**|
| **벤치마크 척도** | **TPC-C, TPC-E (tpmC)** | **SPECweb, SPECjbb (bops)** | **TB per Hour (배치 완료 시간)** |
| **보정 핵심 요소** | N-1 이중화 마진, 복합 트랜잭션 가중치| Keep-Alive 세션 유지, GC 오버헤드 | 월말/분기말 대량 데이터 집중 계수 |

#### 한줄 요약
- OLTP는 TPS/tpmC, WEB/WAS는 동시 사용자/히트수, 배치는 레코드수/배치 윈도우를 기준으로 산정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **하드웨어 규모 산정 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 초당 트랜잭션(TPS)과 분당 트랜잭션(tpmC)의 60배 단위 환산을 누락하여 **하드웨어 요구 스펙을 60배 과소 또는 과대 산정하는 치명적 계산 착오 발생** | **$\text{tpmC} = TPS \times 60 \times C_{weight}$ 공식에 따라 초 단위를 분 단위로 정확히 환산하는 검증 스크립트 강제** | 60배 규모 산정 오차 원천 차단 |
| 카탈로그상의 이론적 tpmC 수치만 믿고 장비를 도입했으나 **실제 애플리케이션의 비효율적 Full Scan 쿼리로 인해 목표 TPS의 30%만 수용하고 다운** | **표준 벤치마크 참조와 병행하여 실제 운영 DB 덤프와 쿼리를 탑재한 실물 BMT(Benchmark Test) 필수 수행** | 실제 업무 적합성 100% 검증 및 오픈 장애 방지 |
| 고가용성을 위해 2대 액티브-액티브 클러스터를 구성했으나 **1대 장애 시 잔여 1대의 용량이 부족하여 연쇄 다운(Cascading Failure) 발생** | **N-1 이중화 보정 기준을 적용하여 단일 서버가 전체 피크 부하를 100% 수용할 수 있도록 서버당 코어 용량 산정** | 단일 노드 셧다운 시에도 무중단 가용성 100% 보장 |

#### 한줄 요약
- 60배 단위 환산을 철저히 검증하고, 실물 BMT로 실제 쿼리를 시험하며, N-1 보정으로 고가용성을 보장한다.

## Ⅶ. 결론

- 공공 및 엔터프라이즈 정보시스템의 성능, 가용성, 경제성을 과학적으로 보증하는 표준 엔지니어링 프레임워크인 **TPS 기반 하드웨어 규모 산정 체계**는 인프라 투자의 타당성을 입증하고 시스템 오픈 장애를 예방하는 핵심 절차이며, 실무 구현 시 **TTA 및 행정안전부 고시 표준 수식의 엄격한 준수**, **피크 계수($F_{peak}$) 및 연평균 성장률($g$)의 현실적 반영**, **목표 가동률 70% 이하 및 N-1 고가용성 마진 통제**, **이론치와 실물 BMT 벤치마크의 교차 검증**을 완성하여 최고 수준의 비용 효율성과 예측 가능한 시스템 가용성을 완성

#### 한줄 요약
- TTA 표준 공식과 4대 보정 계수 및 BMT 검증을 통해 최적의 하드웨어 규모 산정을 완성한다.
