## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소프트웨어 신뢰도 성장 모델(SRGM: Software Reliability Growth Model / NHPP 기반)**: 소프트웨어 시스템 통합 테스트 단계에서 시간이 경과함에 따라 발견되고 수정되는 결함(Defect) 시계열 데이터를 수학적 확률 과정(비동차 포아송 과정, NHPP)으로 모델링하여, 시스템의 총 잠재 결함 수($a$), 결함 검출률($b$), 잔존 결함 수($a - m(t)$), 그리고 목표 신뢰도(MTBF)에 도달하는 최적의 상용 소프트웨어 출시 시점(Optimal Release Time)을 통계적으로 산출하는 품질 공학 방법론.
- **주관적 일정 압박에 따른 조기 출시 및 잠재 결함 누출 결함(Premature Release & Subjective Sizing Defect)**: 객관적인 통계적 품질 검증 없이 사업 일정이나 관리자의 직관에 의해 테스트를 조기 종료하고 상용 배포를 강행하여, 오픈 직후 치명적인 잠재 버그가 동시다발적으로 폭발하며 서비스가 마비되는 구조적 결함.

</details>

- 정의/개념: 소프트웨어 출시의 기술적 타당성과 경제성을 수학적으로 입증하기 위해 **테스트 실행 시간 및 결함 발생 타임스탬프 수집 $\rightarrow$ NHPP 기반 SRGM 모델(G-O / Yamada S자) 적합 $\rightarrow$ 최대우도추정(MLE) 기반 모수($a, b$) 산출 $\rightarrow$ 잔존 결함 수 및 미래 MTBF 예측 $\rightarrow$ 총비용 최소화 기준 최적 출시 시점 확정** 을 집행하는 **통계적 소프트웨어 품질 거버넌스 체계**
- 배경/필요성: 테스트를 무한정 지속할 경우 프로젝트 비용이 초과되고, 조기 종료 시 잠재 결함으로 인한 장애 손실이 발생하므로, 테스트 비용과 사후 장애 비용의 합이 최소가 되는 최적 릴리스 시점 도출 필수

#### 한줄 요약
- SRGM은 테스트 중 결함 발견 추세를 NHPP 모델로 분석하여 잠재 결함 수와 최적의 소프트웨어 출시 시점을 예측한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **SRGM 2대 핵심 통계 수식 함수**:
  - **누적 결함 기댓값 함수 ($m(t)$, Mean Value Function)**: 테스트 시간 $t$까지 발견된 총 결함 수의 기댓값 (시간 $t \to \infty$ 시 총 잠재 결함 수 $a$에 수렴).
  - **고장 강도 함수 ($\lambda(t)$, Failure Intensity Function)**: 단위 시간당 결함이 발견되는 순간 발생률 ($\lambda(t) = \frac{d m(t)}{dt}$).

</details>

- **비동차 포아송 과정(NHPP: Non-Homogeneous Poisson Process) 준거**: 결함이 수정됨에 따라 시스템의 고장 발생 강도($\lambda(t)$)가 시간에 따라 지속적으로 감소하는 현실적 특성 모델링
- **테스터 학습 곡선(Learning Curve) 반영**: 테스트 초기에는 결함 발견율이 서서히 증가하다가 점차 지수적으로 감소하는 S자형(Yamada Delayed S-shaped) 성장 곡선 지원
- **불완전 디버깅(Imperfect Debugging) 보정**: 결함을 수정하는 과정에서 새로운 2차 결함이 재유입될 확률($\alpha$)을 수학적 모수로 보정하여 예측 정확도 극대화

#### 한줄 요약
- NHPP 기반 고장 강도 감쇠, 테스터 학습 효과(S자 곡선) 반영, 불완전 디버깅 보정, 통계적 최적 릴리스 결정을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대표적 SRGM 3대 수리 모델 비교**:
  1. **J-M 모델 (Jelinski-Moranda)**: 결함 제거 시마다 고장률이 일정한 상수 $\phi$만큼 계단식으로 감소.
  2. **G-O 모델 (Goel-Okumoto 지수형)**: 결함 발견이 지수적으로 감소: $m(t) = a(1 - e^{-bt})$, $\lambda(t) = ab e^{-bt}$.
  3. **Yamada S자형 모델 (Delayed S-shaped)**: 학습기 후 결함 감소: $m(t) = a(1 - (1+bt)e^{-bt})$, $\lambda(t) = a b^2 t e^{-bt}$.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 소프트웨어 신뢰도 성장 곡선 비교 (G-O 지수형 vs Yamada S자형) ]    │
│                                                                         │
│   누적 결함수 m(t) │                                  [총 잠재 결함 수 a]│
│                 a ─┼───────────────────────────────- - - - - - - - - -  │
│                   │                . ─── G-O 지수형 모델                │
│                   │            . '                                      │
│                   │        . '         . ─── Yamada S자형 (학습 곡선)   │
│                   │     . '        . '                                  │
│                   │   . '       . '                                     │
│                   │  /       . ' (초기 테스터 학습 기간)                 │
│                   └─┴───────┴──────────────────────────────────────►    │
│                    0       t_opt (최적 출시 시점)              시간 (t) │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (비용 및 신뢰도 최적화 연계)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 최적 출시 시점 결정 수리 모델 (Optimal Release Time Decision) ]     │
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ $\text{Total Cost } C(T) = C_1 \times T + C_2 \times m(T) + C_3 \times (a - m(T))$ │
│  └───────────────────────────────────────────────────────────────────┘  │
│  ├─ $C_1$: 단위 시간당 소프트웨어 테스트 비용 ($/hour)                  │
│  ├─ $C_2$: 테스트 중 결함 1건 수정 비용 ($/defect)                      │
│  ├─ $C_3$: 상용 배포 후 운영 중 결함 1건 수정 및 장애 손실 비용 ($3 \gg C_2$)│
│  └─ $\text{Optimal Time } T^*$: $\frac{dC(T)}{dT} = 0$을 만족하는 총비용 최소 시점│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 테스트 진행에 따라 누적 결함이 총 잠재 결함수 $a$에 수렴하며, 테스트 비용과 사후 장애 비용의 합이 최소가 되는 시점을 도출하는 구조

| 모델 컴포넌트 | 수학적 정의 및 공식 | 특성 및 가정 | 비고 |
|:---|:---|:---|:---|
| **G-O 모델** | $m(t) = a(1 - e^{-bt})$ | 결함 검출률($b$)이 상시 일정하며 지수 감쇠 | Exponential |
| **Yamada S자형** | $m(t) = a(1 - (1+bt)e^{-bt})$| 초기 테스터의 학습 효과로 검출률이 상승 후 감소 | S-shaped |
| **잠재 결함수 ($a$)** | $\lim_{t \to \infty} m(t) = a$ | 시스템 내부에 존재하는 초기 총 소프트웨어 버그 수 | Parameter |
| **결함 검출률 ($b$)** | 단위 시간당 버그 검출 능력 | 테스터의 숙련도 및 테스트 자동화 도구 효율성 | Parameter |
| **순간 고장 강도** | $\lambda(t) = m'(t)$ | 특정 시간 $t$ 시점의 초당 버그 발생 빈도 | Intensity |

#### 한줄 요약
- G-O 모델, Yamada S자형 모델, 잠재 결함수($a$), 결함 검출률($b$), 총비용 최소화($C(T)$) 공식으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SRGM 적용 및 최적 출시 결정 5단계 엔지니어링 프로세스**:
  1. 통합 테스트 단계에서 일별/시간별 결함 발생 건수 및 CPU 테스트 시간 수집
  2. 수집된 결함 데이터 분포가 S자형인지 지수형인지 패턴 분석 후 적합 모델 선정
  3. 최대우도추정법(MLE: Maximum Likelihood Estimation)을 통해 모수 $a, b$ 수치 산출
  4. 카이제곱($\chi^2$) 또는 K-S 검정을 통해 모델 적합도(Goodness of Fit) 검증
  5. 목표 MTBF 및 허용 잔존 결함 밀도($\le 0.1\text{ defects/KLOC}$) 충족 시 출시 승인

</details>

```text
1. [테스트 텔레메트리 결함 데이터 수집]
    ├─ 4주간의 통합 테스트 수행: 매일 발견된 결함 수 및 누적 테스트 시간(t) 기록
    └─ [수집 데이터: Day 1~7 (120건), Day 8~14 (350건), Day 15~21 (210건), Day 22~28 (80건)]
            │
            ▼
2. [데이터 형태 분석 및 Yamada S자 모델 선정]
    ├─ 초반 1주 차에 결함 발견이 적다가 2주 차에 급증 후 4주 차에 급감하는 S자 패턴 식별
    └─ [결정: 초기 학습 효과를 반영하는 'Yamada Delayed S-shaped 모델' 채택]
            │
            ▼
3. [최대우도추정(MLE) 기반 모수 도출]
    ├─ 비선형 연립방정식 풀이 (Newton-Raphson 수치 해석)
    ├─ 총 잠재 결함 수: $a = 850\text{건}$ 도출
    ├─ 결함 검출률 모수: $b = 0.142 \text{ /day}$ 도출
    └─ [현재 28일 차 누적 발견 결함: $m(28) = 760\text{건}$ ➔ 잔존 결함 $a - m(28) = 90\text{건}$]
            │
            ▼
4. [통계적 적합도 검정 (Goodness of Fit)]
    ├─ 카이제곱($\chi^2$) 적합도 검정 수행 ➔ 유의확률 $p = 0.92 > 0.05$ 통과
    └─ [실측 데이터와 모델 예측 곡선의 상관계수 $R^2 = 0.985$ (극도로 높은 적합도 확인)]
            │
            ▼
5. [최적 출시 시점 판정 및 배포 승인]
    ├─ 목표 기준: 잔존 결함 20건 이하 AND 순간 고장 강도 $\lambda(t) \le 1.0\text{ bug/day}$
    ├─ 모델 시뮬레이션: 추가 테스트 10일 더 수행 시 $t=38\text{일}$에 조건 100% 충족 예측
    └─ [조치: 테스트 기간을 10일 연장 확정 ➔ 38일 차에 신뢰도 목표 달성 후 무결점 상용 출시]
```

**동작 원리**

1. **최대우도추정법(MLE)의 정밀성**: 우도 함수(Likelihood Function)의 로그를 취하고 편미분하여 현재 관측된 결함 데이터가 나타날 확률을 극대화하는 모수 $a, b$를 오차 없이 산출
2. **사후 유지보수 비용 폭증 방어**: 배포 후 결함 수정 비용($C_3$)은 테스트 중 수정 비용($C_2$)보다 통상 10배~100배 이상 비싸므로, 통계적으로 충분한 테스트 시간을 수학적으로 보장
3. **운영 프로파일(Operational Profile) 연계**: 단순 단위 테스트가 아닌 실제 운영 환경의 사용자 트랜잭션 비율을 모사한 테스트 데이터를 입력해야만 예측의 현실성 보장
4. **잔존 결함 밀도(Residual Defect Density) 정량화**: 출시 시점에 코드 1,000 라인당 남아있는 버그 수(KLOC당 결함 수)를 예측하여 경영진에 객관적 품질 증거 제시
5. **불완전 디버깅 위험 통제**: 버그를 수정할 때 새로운 버그가 유입되어 $m(t)$ 곡선이 우상향으로 튀는 현상을 감지하여 개발자 코드 리뷰 프로세스 강화

#### 한줄 요약
- 데이터 수집, S자형 모델 선정, MLE 모수($a, b$) 산출, 적합도 검정, 목표 MTBF 도달 시 출시 승인 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SRGM 3대 모델별 특성 및 가정 비교**:
  - J-M (Jelinski-Moranda): 이산형, 버그마다 고장률 고정 감소 (초기 이론 모델).
  - G-O (Goel-Okumoto): 연속형 지수 감소, 버그 발견율 상시 일정 (표준 모델).
  - Yamada S자형 (Delayed S-shaped): 초기 테스터 학습 지연 반영 (현대 실무 최고 적합).

</details>

| 비교 항목 | J-M 모델 (Jelinski-Moranda) | G-O 모델 (Goel-Okumoto) | Yamada S자형 모델 (Delayed S-shaped) |
|:---|:---|:---|:---|
| **수학적 기반** | **이산형 마르코프 과정 (Discrete)**| **연속형 비동차 포아송 과정 (NHPP)**| **연속형 비동차 포아송 과정 (NHPP)** |
| **누적 결함 수 $m(t)$**| 계단식 불연속 함수 | $a(1 - e^{-bt})$ (지수 수렴) | $a(1 - (1+bt)e^{-bt})$ (S자 수렴) |
| **고장 강도 $\lambda(t)$**| $\phi(N - (i-1))$ | $ab e^{-bt}$ (단조 감소) | $a b^2 t e^{-bt}$ (증가 후 감소) |
| **테스터 학습 효과**| 미반영 (초기부터 고속 발견 가정) | 미반영 (초기부터 고속 발견 가정)| **완벽 반영 (초기 학습 지연 모델링)**|
| **실무 적합성** | 낮음 (가정이 너무 단순함) | 보통 (안정된 테스트 조직에 적합)| **최고 우수 (대부분의 실제 프로젝트)**|

#### 한줄 요약
- J-M은 이산형 기초, G-O는 지수형 표준, Yamada는 학습 곡선을 반영한 S자형 최고 실무 적합 모델이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SRGM 실무 적용 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 버그를 수정하면서 새로운 버그를 유입(불완전 디버깅)시켜 **결함 발견율이 줄어들지 않고 누적 결함이 발산하여 출시 시점 예측 불가** | **불완전 디버깅 모수($\alpha$)를 포함한 확장 SRGM(P-N-Z 모델 등)을 적용하고 결함 수정 코드에 대한 필수 코드리뷰 강제** | 2차 버그 유입 보정 및 정확한 수렴 예측 달성 |
| 단순 기능 테스트 데이터만 입력하여 **실제 운영 피크 환경에서의 동시성 락(Lock) 결함 및 부하 결함을 전혀 예측하지 못하는 왜곡 발생** | **실제 사용자 트래픽 믹스를 모사한 운영 프로파일(Operational Profile) 기반의 성능 부하 시험 데이터를 SRGM 입력으로 활용** | 실사용 환경 신뢰도 예측 정확도 95% 확보 |
| 경영진의 고정 출시 마감일(Deadline) 압박으로 인해 **잔존 결함 수가 200건 이상임에도 강제 배포를 감행하여 오픈 당일 대형 장애 발생** | **총비용 최소화 공식($C(T)$)에 기반하여 "지금 출시 시 사후 장애 처리 비용 10억 원 vs 1주일 연장 시 5천만 원"의 정량적 리스크 보고** | 경영진의 합리적 출시 연기 승인 및 품질 사수 |

#### 한줄 요약
- 불완전 디버깅 모수로 보정하고, 운영 프로파일로 실 부하를 시험하며, 비용 곡선으로 출시 일정을 방어한다.

## Ⅶ. 결론

- 감정이나 직관에 의존하던 소프트웨어 출시 결정을 수학적 통계 데이터에 기반한 과학적 엔지니어링으로 혁신하는 **신뢰도 성장 모델(SRGM) 체계**는 프로젝트의 비용 최적화와 상용 서비스의 무결점 품질을 동시에 견인하는 핵심 나침반이며, 실무 구현 시 **NHPP 기반의 Yamada Delayed S자형 모델 적용**, **최대우도추정법(MLE)을 통한 잠재 결함($a$) 및 검출률($b$) 산출**, **운영 프로파일 기반의 결함 데이터 정제**, **총비용 최소화 수식($C(T)$)과 목표 MTBF 기준의 정량적 출시 승인**을 완성하여 최고 수준의 소프트웨어 신뢰성과 무결점 릴리스 거버넌스를 완성

#### 한줄 요약
- NHPP 기반 Yamada S자형 SRGM과 MLE 모수 추정을 통해 최적의 소프트웨어 출시 시점을 완성한다.
