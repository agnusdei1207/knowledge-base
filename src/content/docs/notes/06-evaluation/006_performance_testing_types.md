## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 테스트(Performance Testing)**: 실제 환경 부하 재현을 통해 처리량, 지연시간, 오류율 등을 정량적으로 검증하는 활동.
- **서비스 수준 목표(Service Level Objective, SLO)**: 성능 테스트 합격 여부를 판정하기 위한 정량적 목표 지표.
- **성능 테스트 유형(Performance Testing Types)**: 부하 패턴과 지속 시간을 통제하여 다양한 장애 시나리오를 검증하는 테스트 분류 체계.

</details>

- 정의/개념: 부하 형태와 인가 시간을 다양화하여 시스템의 용량 한계와 복원력을 검증하는 성능 평가 기법
- 배경/필요성: 단일 부하 시험만으로는 **자원 누수·순간 폭주·회복성** 검증 불가

#### 한줄 요약

- 운영 부하를 재현해 **한계·붕괴 요소 선제 진단** ## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **부하 패턴(Load Pattern)**: 동시 접속 가상 사용자 수, 요청률, 증가율 등을 조합하여 구성한 트래픽 인가 형태.
- **99백분위수(99th Percentile Latency, p99)**: 꼬리 지연 악화를 감시하는 통계 지표.
- **자원 포화(Resource Saturation)**: 서버 처리 한계 초과로 인한 대기열 누적 및 오류 상태.
- **회복성(Resilience)**: 과부하 해소 직후 지연과 오류율이 평시 수준으로 자력 복구되는 역량.

</details>

- 강도·증가율·지속시간으로 **부하 패턴** 구분
- 실제 업무 비율·데이터 분포로 운영 부하 재현
- **p99·자원 포화·회복성** 함께 관측

#### 한줄 요약

- 최대 용량·장기 열화·**폭주 후 회복력 검증** ## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워크로드 모델(Workload Model)**: API 호출 빈도, 접근 패턴 등을 실제 운영 부하와 흡사하게 조합한 모형.
- **부하 생성기(Load Generator)**: 워크로드 프로파일에 따라 가상 사용자 요청을 수행하는 엔진.
- **판정 기준(Acceptance Criteria)**: 테스트 통과를 위한 정량적 임계선.

</details>

```text
             [목표•업무 시나리오]
                       |
        [부하 패턴•프로파일]---[시험 환경•데이터]
                    |                    |
        [지연•오류•자원 지표]---[중단•복구•판정 기준]
```

선의 의미: 목표·부하·환경·지표·판정 기준의 상호 연계 구조.

| 구성요소 | 책임 |
|:---|:---|
| 목표•업무 시나리오 | SLO·거래·위험 범위 정의 |
| 부하 패턴•프로파일 | **워크로드 모델**·증가율·시간 설계 |
| 시험 환경•데이터 | **부하 생성기**·환경·데이터 통제 |
| 지연•오류•자원 지표 | 모니터링으로 p99·포화 수집 |
| 중단•복구•판정 기준 | **판정 기준** 기반 합격 여부 결정 |

#### 한줄 요약

- 워크로드 결과와 **합격 임계선 대조** ## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **회복 검증(Recovery Verification)**: 과부하 중단 후 대기열 해소와 지연시간 정상화 복원력을 계측하는 절차.
- **시험 재현성(Test Reproducibility)**: 동일 조건에서 일관된 성능 결과가 재현됨을 보증하는 성질.

</details>

```text
시험 책임자
   │ 목표·유형·합격 기준 전달
   ▼
시험 제어기·부하 발생기
   │ 1. 환경·데이터·부하 설정 검증
   │ 2. 부하 증가·유지·급변 실행
   ▼
시험 대상·관측 계층
   │ 3. 지연·오류·포화·복구 지표 수집
   ▼
시험 제어기
   │ 4. 합격 기준 판정·병목 분석
   ▼
합격 여부·위험·재시험 조건
```

**동작 원리** 1. **환경·데이터·부하 설정 검증**: 재현 조건 확인
2. **부하 증가·유지·급변 실행**: 유형별 부하 인가
3. **지연·오류·포화·복구 지표 수집**: 회복 증거 수집
4. **합격 기준 판정·병목 분석**: 출시·재시험 결정

#### 한줄 요약

- 통제된 부하와 **지연·포화·회복 지표 판정** ## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **부하 테스트(Load Testing)**: 예상 피크 부하에서 SLO 충족 여부를 검증하는 기본 성능 진단.
- **스트레스 테스트(Stress Testing)**: 수용 한계를 초과하는 부하로 붕괴점(파괴점)과 복구력을 검증하는 시험.
- **소크 테스트(Soak Testing)**: 장시간 일정 부하로 메모리 누수와 자원 고갈 결함을 검증하는 내구 시험.
- **스파이크 테스트(Spike Testing)**: 순간적인 트래픽 폭증 시 시스템 대응력과 정상 복귀를 검증하는 시험.

</details>

| 테스트 유형 | 부하 테스트 (Load) | 스트레스 테스트 (Stress) | 소크 테스트 (Soak) | 스파이크 테스트 (Spike) |
|:---|:---|:---|:---|:---|
| 적용 기준 | **목표 성능** 충족 검증 | **파괴점**·한계 용량 확인 | **누수·열화 결함** 탐지 | **순간 급증 대응력** 확인 |
| 핵심 특징 | 목표 부하 일정 시간 유지 | 붕괴점까지 점진적 부하 증가 | 안정 부하 장시간 유지 | 부하 순간 급증 후 급감 |
| 한계 | 한계 파괴점 미확인 | 복구 불능 시 원인 분석 난항 | 장시간 환경 점유 비용 | 부하 발생기 자체 포화 위험 |

> 요약: 비즈니스 운영 특성에 따라 위험 요소를 세분화하여 적합한 성능 테스트 유형을 구분 적용.

#### 한줄 요약

- 평시·파괴·장기·급증 위험별 **시험 유형 선택** ## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **업무 비율(Transaction Mix)**: 실제 운영 트랜잭션 비율을 분석해 조합한 가상 부하 구성.
- **시험 격리(Test Environment Isolation)**: 성능 테스트가 운영 환경에 미치는 영향을 차단하는 통제 조치.
- **발생기 자체 포화(Load Generator Saturation)**: 부하 발생 도구의 자원 고갈로 인한 측정 왜곡 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 API로 실제 병목 누락 | 로그 기반 **업무 비율** 재현 | 운영 병목 오차 감소 |
| 혼재 환경의 노이즈 간섭 | 전용 환경의 **시험 격리** | 비교 기준 일관성 확보 |
| 부하 도구가 지연 생성 | **발생기 자체 포화** 동시 감시 | 원인 오판 방지 |

#### 한줄 요약

- 티켓팅은 실제 업무 비율의 **스파이크 재현** ## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **파괴점(Break-point)**: 부하 증가 시 응답시간이 폭증하거나 오류가 발생하기 시작하는 성능 한계점.

</details>

- 평시는 부하, 한계는 스트레스, 장기는 소크, 급증은 스파이크 테스트 적용

#### 한줄 요약

- 이벤트 급증은 스파이크로 **회복성 검증**
