## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 테스트 4대 핵심 유형(Performance Testing Types)**: 소프트웨어 시스템이 운영 환경에서 직면할 수 있는 다양한 트래픽 조건(정상 피크, 한계 초과, 장시간 가동, 순간 폭주)을 인위적으로 모사하여 처리량(TPS), 응답시간(p99 지연), 파괴점(Break Point), 자원 누수(Memory Leak), 그리고 장애 복원력(Resilience)을 입체적으로 검증하는 성능 엔지니어링 방법론.
- **단일 부하 시험 편향에 따른 잠재 결함 은폐 결함(Single Load Test Blind Spot Defect)**: 1~2시간 동안의 단순 부하 테스트(Load Test)만을 통과한 후 상용 배포했을 때, 며칠 뒤 메모리 누수로 서버가 다운(Soak 미수행)되거나 대규모 이벤트 시 순간 트래픽 폭증으로 오토스케일링이 반응하기도 전에 클러스터 전체가 연쇄 붕괴(Spike/Stress 미수행)되는 구조적 결함.

</details>

- 정의/개념: 부하 강도와 지속시간별 **용량·한계** 검증 시험 및 장기 부하와 순간 폭주에 대한 **내구성·복원력** 종합 검증 체계
- 배경/필요성: 1~2시간 동안의 단순 부하 테스트(Load Test)만을 통과한 후 상용 배포할 경우, 장시간 운영 시 누적되는 메모리 누수(Memory Leak)와 DB 커넥션 풀 고갈을 사전에 식별하지 못해 며칠 뒤 서버가 다운되거나 대규모 마케팅 이벤트 시 순간 폭주 트래픽으로 인해 오토스케일링이 반응하기도 전에 클러스터 전체가 연쇄 붕괴되는 구조적 결함이 발생함에 따라, 부하 강도와 지속시간을 축으로 부하(Load), 스트레스(Stress), 소크(Soak), 스파이크(Spike) 시험을 유기적으로 결합하는 4대 성능 테스트 체계를 도입하여 **예상 피크 처리량(SLO) 검증, 시스템 처리 한계(Knee Point)와 완전 파괴점(Break Point) 탐색, 장시간 내구성 및 서킷 브레이커 장애 복원력(Resilience)**을 달성할 필요

#### 한줄 요약
- 성능 테스트는 부하(Load), 스트레스(Stress), 소크(Soak), 스파이크(Spike) 시험을 통해 용량과 복원력을 종합 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **4대 성능 테스트 핵심 목적 및 부하 프로파일**:
  - **부하 테스트 (Load Testing)**: 예상되는 최대 피크 트래픽 환경에서 SLO(예: 3,000 TPS, p99 < 500ms) 충족 여부 확인.
  - **스트레스 테스트 (Stress Testing)**: 시스템이 견딜 수 있는 최대 한계(Knee Point)와 완전 붕괴(Break Point) 지점 탐색.
  - **소크 테스트 (Soak / Endurance Testing)**: 24시간~72시간 동안 일정 부하를 연속 주입하여 메모리/커넥션 누수 색출.
  - **스파이크 테스트 (Spike Testing)**: 0에서 피크의 3~5배 부하를 수 초 만에 인가하여 서킷 브레이커 및 복구력 검증.

</details>

- 강도·지속시간 조합으로 구분하는 **4대 부하 프로파일**
- 처리량 둔화와 오류 급증을 구분하는 **Knee·Break Point**
- 폭주 종료 후 정상 응답 복귀를 측정하는 **복원력**

#### 한줄 요약
- 부하·스트레스·소크·스파이크의 다각적 조합, 한계 파괴점 식별, 자가 회복력 검증을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성능 테스트 4대 아키텍처 및 부하 곡선 패턴**:
  1. **Load Test Curve**: 점진적 증가(Ramp-up) $\rightarrow$ 피크 부하 유지(Plateau) $\rightarrow$ 종료.
  2. **Stress Test Curve**: 한계 도달 시까지 지속적 계단식 증가(Step-up) $\rightarrow$ 붕괴 관측.
  3. **Soak Test Curve**: 기준 부하(70~80%)로 장시간(24~72시간) 플랫(Flat) 유지.
  4. **Spike Test Curve**: 평시 부하 $\rightarrow$ 수직 상승(Spike) $\rightarrow$ 급강하 $\rightarrow$ 정상 회복 관측.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 부하 테스트 | 예상 피크에서 **SLO** 충족 여부 검증 |
| 스트레스 테스트 | 처리 한계와 **붕괴 지점** 탐색 |
| 소크 테스트 | 장시간 **자원 누수**와 성능 저하 탐지 |
| 스파이크 테스트 | 순간 폭주 대응과 **정상 복귀** 검증 |

#### 한줄 요약
- 네 시험은 부하 곡선의 강도 축과 지속시간 축 중 어느 쪽을 흔드는지로 갈리므로, 강도만 올리는 부하·스트레스만 돌리면 24~72시간을 지나야 드러나는 누수는 시험이 아니라 운영 중 장애로 발견하게 된다.

## Ⅳ. 흐름도

```text
[검증할 위험 선택]
    |
    +-- 예상 피크의 목표 성능인가?
    |      `-- 1. 부하 테스트
    |
    +-- 처리 한계와 붕괴점인가?
    |      `-- 2. 스트레스 테스트
    |
    +-- 장시간 누적 결함인가?
    |      `-- 3. 소크 테스트
    |
    `-- 순간 폭주 후 복구인가?
           `-- 4. 스파이크 테스트
```

**동작 원리**

1. **부하 테스트**: 예상 피크에서 SLO 충족 여부 판정
2. **스트레스 테스트**: 계단식 증설로 Knee·Break Point 탐색
3. **소크 테스트**: 안정 부하를 장시간 유지해 자원 누수 탐지
4. **스파이크 테스트**: 급격한 부하 변화 후 정상 복귀시간 측정

#### 한줄 요약
- 목표 성능·처리 한계·장기 누수·순간 복구 중 검증할 위험에 따라 시험 유형을 고른다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **성능 테스트 4대 유형 비교**:
  - Load: 목표 SLA 검증 (적합성 확인).
  - Stress: 한계 및 붕괴점 탐색 (강인성 확인).
  - Soak: 장시간 자원 누수 검증 (내구성 확인).
  - Spike: 트래픽 급증 및 복원력 검증 (탄력성 확인).

</details>

| 비교 항목 | 부하 테스트 | 스트레스 테스트 | 소크 테스트 | 스파이크 테스트 |
|:---|:---|:---|:---|:---|
| 적용 목적 | **목표 SLO** 충족 확인 | **Knee·Break Point** 탐색 | **자원 누수** 탐지 | **탄력적 복원** 검증 |
| 부하 형태 | **예상 피크** 부하 유지 | 한계까지 **계단식 증가** | **안정 부하** 장시간 유지 | **순간 극한 부하** 인가 |
| 판정 지표 | **TPS·p99 응답시간** | **처리량·오류율** | **메모리·연결 수** 추이 | **정상 회복시간·오류 격리** |

#### 한줄 요약
- 부하는 목표 적합성, 스트레스는 파괴 한계, 소크는 장기 내구성, 스파이크는 순간 복원력을 검증한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **성능 테스트 실무 수행 시 3대 위험 요소와 엔지니어링 대책**:

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 API 반복으로 **트랜잭션 경합** 누락 | 운영 로그 기반 **트랜잭션 믹스** 재현 | **운영 병목** 식별 |
| 부하 발생기 포화로 **측정 왜곡** 발생 | 발생기 자원과 **주입률** 동시 감시 | **대상 병목**과 분리 |
| 축소 데이터로 **I/O 지연** 과소평가 | 운영 동급 **데이터 볼륨** 구성 | **인덱스·I/O** 검증 |

#### 한줄 요약
- 트랜잭션 믹스로 실 부하를 모사하고, 부하 도구 포화를 방어하며, 운영 동급 데이터 볼륨으로 검증한다.

## Ⅶ. 결론

- 다양한 트래픽 조건과 극한의 부하 환경을 사전에 시뮬레이션하여 시스템의 용량 한계와 장기적 안정성을 다각도로 입증하는 **시스템 한계 및 내구성 종합 검증(Performance Testing / Load·Stress·Soak·Spike / Break Point & Resilience)의 핵심 품질 엔지니어링 표준**으로 확고히 자리 잡았으며, 카오스 엔지니어링(Chaos Engineering) 및 CI/CD 성능 게이트 자동화로 진화하는 가운데, 실무 성능 검증 계획 수립 시에는 **운영 로그 기반 실제 트랜잭션 믹스(Transaction Mix) 재현, 장시간(24~72시간) 소크 테스트를 통한 메모리 누수 전수 검증, 스파이크 부하 인가 후 서킷 브레이커 동작 및 정상 상태 복귀 시간(Recovery Time) 정량 평가**를 결합하여 완벽한 시스템 복원력을 완성

#### 한줄 요약
- 4대 성능 테스트 유형의 입체적 연계를 통해 시스템 처리 용량과 장애 복원력을 완벽하게 검증한다.
