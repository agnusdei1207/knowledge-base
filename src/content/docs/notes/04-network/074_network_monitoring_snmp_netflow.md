## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 모니터링 (Network Monitoring)**: 망이 터졌을 때 "어디가 죽었냐(SNMP)", "누가 범인이냐(NetFlow)", "무슨 데이터냐(sFlow)"를 다방면으로 털어서 장애 원인을 체크하는 관제 시스템이다.
- **SNMP (단순 네트워크 관리 프로토콜)**: 관제 서버가 라우터나 스위치한테 "너 지금 CPU 몇 %야? 포트 살았냐?" 하고 상태(Health)를 물어보는 가장 기본적인 청진기 프로토콜이다.

</details>

- 정의: **네트워크 모니터링** **SNMP** 기반 장비의 건강 상태를 캐묻고, **NetFlow/sFlow** 기반 트래픽 흐름과 패킷 샘플을 떠서 장애 원인을 교차 검증하는 입체적 관측 체계다.
- 배경: 라우터 CPU가 100% 쳤다는 단순 경보(SNMP)만으로는 "어떤 놈이 사내망에서 토렌트 다운받아서 터졌는지" 진짜 범인을 잡을 수 없어서, **트래픽 흐름과 표본까지 같이 털어보는 종합 관제 시스템이 필수 불가결해졌다.**

#### 한줄 요약

- 장비가 죽었는지 확인하는 청진기(SNMP)와 트래픽 범인을 잡는 CCTV(NetFlow)를 합쳐서 망을 감시하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **신호 결합 (Correlation)**: SNMP가 "1시 정각에 CPU 터짐"을 알렸을 때, NetFlow에서 "1시 정각에 A팀 PC에서 10기가 트래픽 쏨"이라는 증거를 같은 시간대(타임라인)로 묶어서 빼도 박도 못하게 범인을 확정 짓는 과학수사 기법이다.

</details>

- **입체적 교차 검증**: 하나의 지표만 믿지 않고, 장비 상태(SNMP), 통신 주체(NetFlow), 패킷 표본(sFlow) 세 가지 증거를 모아서 사건의 퍼즐을 맞춘다.
- **시간축 일치 (신호 결합)**: 관제 서버가 수집한 이질적인 데이터를 같은 시간대(Time-sync)로 묶어서, 장비가 뻗은 시간과 특정 IP의 트래픽 폭주 시간을 완벽하게 연결해 낸다.
- **수집 오차 방어**: 장비가 갑자기 재부팅돼서 카운터가 0으로 꼬이거나 데이터가 유실되는 걸 막기 위해, 순번(Sequence)과 템플릿을 철저하게 검사한다.

#### 한줄 요약

- 똑같은 사고라도 SNMP는 총량을, NetFlow는 범인 IP를, sFlow는 패킷 내용을 보여주니 이걸 다 묶어서 수사한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **에이전트(Agent) / 익스포터(Exporter)**: 공유기나 라우터 안에서 끄적끄적 장비 상태나 트래픽 내역을 적어서 관제 서버로 던져주는(Export) 내부 스파이 요원들이다.
- **컬렉터 (Collector)**: 전국 장비 요원들이 던진 데이터를 한군데 모아서 분석하고, 모니터에 그래프 띄워주는 중앙 관제 센터(NMS 서버)다.

</details>

```text
[ 네트워크 관제 직관적 비교 구조 ]

[ 1. 장비 (에이전트 / 익스포터) ] ── (라우터 내부에서 CPU 온도 재고, 지나가는 패킷 기록함)
      │
      ▼ (로그 쏜다!)
[ 2. 수집기 (컬렉터) ] ── (전국 라우터에서 날아오는 로그 싹 다 긁어모음)
      │
      ▼
[ 3. 정규화 및 상관 분석 ] ── (단위랑 시간대 맞추고 원인-결과 엮어내는 과학수사 돌림)
      │
      ▼
[ 4. 시각화 및 경보 (NMS) ] ── (대시보드에 빨간불 띄우고 관리자한테 "3번 포트 죽음!" 카톡 보냄)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **에이전트 / 익스포터** | 장비 안에서 **자기 상태 찍고 트래픽 기록해서 밖으로 던지는 놈** | Agent / Exporter |
| **수집기 (Collector)** | 전국에서 쏟아지는 **데이터 주워 담고 누락된 거 없나 체크함** | Collector |
| **정규화 및 상관 분석** | "1시에 터진 거 1시에 들어온 트래픽 때문이네" 하고 **범인 연결함** | Analyzer |
| **시각화 및 경보** | 모니터에 그래프 띄우고 **임계치 넘으면 관리자 폰으로 알람 때림** | NMS Dashboard |

#### 한줄 요약

- 라우터가 로그 쏘면 $\to$ 컬렉터가 모아서 $\to$ 시간대 엮어 분석하고 $\to$ 대시보드로 알람 울리는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **OID (객체 식별자)**: SNMP에서 "너 CPU 로드율 몇이냐?" 물어볼 때 쓰는 '1.3.6.1.4.1..' 같은 항목별 고유 번호표(주민번호)다.
- **IPFIX**: 구형 넷플로(NetFlow)를 대체하는 국제 표준 버전으로, "누가 누구한테 몇 기가 쐈다"는 통화 기록을 통일된 규격으로 뽑아내는 프로토콜이다.

</details>

```text
[ 관제 데이터 수집 및 수사 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [SNMP 상태 찌르기 (Polling)]
│ (컬렉터: 야 라우터, OID 1번(CPU) 값 지금 당장 내놔!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [IPFIX / sFlow 레코드 쏘기]
│ (장비: 통신 기록이랑 패킷 샘플 떴습니다. 받으십쇼!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [순번/템플릿 철저한 검증]   │
│ (컬렉터: 중간에 데이터 빠진 거 없지? 템플릿 규격 맞지?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [정규화 및 범인 분석]     │
│ (컬렉터: 시간 맞춰보니 A팀 IP가 범인이네. 즉시 경보 올려!)
└──────────────────────────────┘
```

### 동작 원리

1. SNMP 헬스 체크: 컬렉터가 1분이나 5분 주기로 장비의 **OID** 활용 찔러서 현재 CPU나 포트 에러 카운터를 뽑아옴.
2. 트래픽 흐름/표본 전송: 장비가 알아서 지나가는 트래픽 통화 내역(**IPFIX**)이나 무작위 패킷 표본(**sFlow**)을 컬렉터로 밀어줌.
3. 데이터 무결성 검증: 컬렉터가 날아온 레코드의 순번을 체크해서, 장비가 재부팅돼서 날아가거나 중간에 누락된 게 없는지 검증함.
4. 상관 분석 완료: 장비, 인터페이스, 타임라인을 하나로 통일(정규화)시켜서 원인과 결과를 체크하고 분석기에 넘김.

#### 한줄 요약

- 컬렉터가 상태 찌르고(SNMP), 장비가 기록 쏘면(NetFlow), 순번 체크하고 시간 엮어서 범인 잡는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **sFlow (표본 흐름)**: 지나가는 패킷을 1/1000 확률로 무작위로 뽑아(샘플링) 검문하는 기술이다. 대충 트렌드 파악엔 좋지만 정밀 수사엔 약하다.

</details>

| 구분 | **SNMP (청진기)** | **NetFlow / IPFIX (CCTV)** | **sFlow (랜덤 샘플링)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | "너 어디 아파?" **장비 건강 체크** | "누가 언제 얼마나 쐈어?" **통화 내역서** | "지나가는 놈 아무나 검문" **무작위 검문** |
| 주 수집 데이터 | **OID** 값 (CPU, 메모리, 포트 On/Off) | IP, 포트, 프로토콜, 누적 바이트 **(흐름 주체)** | 설정한 비율로 뽑은 **패킷 원본 표본** |
| 치명적 한계 | 주기적 조회라 **주기 사이 사고 나면 모름** | 트래픽 싹 다 기록하느라 **라우터 CPU 터짐** | 무작위로 뽑아서 **소규모 핵심 해킹 패킷은 놓침** |
| 주력 활용 | 장비 죽었나 살았나 헬스 체크용 (기본 NMS) | 대역폭 누가 다 처먹었나 멱살 잡을 때 (과금/분석) | 100기가망에서 라우터 부하 없이 대충 쓱 훑어볼 때 |

#### 한줄 요약

- 장비 뻗었을 땐 SNMP, 트래픽 폭주 범인 잡을 땐 NetFlow, 초고속망에서 부하 없이 대충 볼 땐 sFlow 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NTP (네트워크 시간 프로토콜)**: 전 세계 장비들의 시계를 초 단위까지 똑같이 맞춰주는 동기화 프로토콜이다. 이거 안 맞으면 과학수사 타임라인이 꼬여서 무죄 판결 난다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 장비 시계 달라서 **범인 잡는 타임라인 꼬여버림 (사건 왜곡)** | 라우터A랑 서버 시계가 5분씩 틀어져서 1시에 터진 게 1시 5분으로 기록돼 증거 기각됨 | 전 장비에 **NTP(시간 동기화) 서버 세팅해서 초 단위까지 싹 다 억지로 맞춤** | 로그 시간 체크 확실해지고 범인 추적 성공률 떡상 |
| NetFlow 켰더니 **라우터 CPU 100% 치고 망 뻗어버림** | 10기가망에서 지나가는 패킷 수천만 개를 다 기록하려니까 라우터 대가리 터짐 | 풀 기록 포기하고 **1/1000 확률로 뽑는 sFlow 샘플링으로 싹 갈아탐** | 라우터 CPU 뻗는 거 막고 관제 시스템 부하 확 낮춤 |
| sFlow 썼더니 **해킹 패킷이 로그에 안 남음 (희소 흐름 누락)** | 무작위로 뽑기 때문에, 패킷 1~2개로 치고 빠지는 소규모 악성 해킹(포트 스캔)은 못 잡음 | 샘플링만 믿지 말고 **방화벽 로그나 SNMP 카운터 크로스 체크(교차 검증) 빡세게 돌림** | 샘플링 놓치는 맹점 보완하고 관제 사각지대 없앰 |

#### 한줄 요약

- 무조건 NTP로 시계부터 똑같이 맞추고, 망 속도 빠르면 라우터 터지니까 풀 기록(NetFlow) 대신 샘플링(sFlow) 써라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 네트워크 장애 원인을 다각도로 분석하기 위해, 장비 상태(**SNMP**), 통신 주체 상세 내역(**NetFlow/IPFIX**), 고속망 저부하 표본(**sFlow**) 수집 방식을 결합한 입체적 관제 기조 확립함

#### 한줄 요약

- 네트워크 모니터링은 단일 증거만으론 범인을 잡을 수 없기에, 상태와 흐름, 표본 데이터를 총동원하는 종합 과학수사 체계다.
