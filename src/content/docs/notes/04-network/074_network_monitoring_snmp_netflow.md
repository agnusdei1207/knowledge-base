## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **네트워크 모니터링(Network Monitoring)**: 상태•흐름•패킷 표본을 수집해 장애 원인을 분석하는 체계이다.
- **단순 네트워크 관리 프로토콜(Simple Network Management Protocol, SNMP)**: 장비의 관리 정보와 상태를 조회•통지하는 프로토콜이다.

</details>

- 정의/개념: **네트워크 모니터링**은 **SNMP** 상태•트래픽 흐름•패킷 표본을 수집해 상관 분석하는 관측 체계이다.
- 배경/필요성: 단일 지표만으로는 장비 장애와 트래픽 원인을 연결할 수 없다.

#### 한줄 요약

- 장비 상태표와 통신 흐름 기록과 패킷 표본을 함께 봐야 장애 원인과 트래픽 주체를 연결할 수 있다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **신호 결합**: 장비 카운터•통신 흐름•패킷 표본을 같은 시간축과 인터페이스 기준으로 연결하는 과정이다.

</details>

- 서로 다른 트래픽 지표를 공통 단위와 시간축으로 변환한다.
- 시각•순번•템플릿을 검사해 수집 오류로 인한 왜곡을 막는다.
- **신호 결합**으로 상태•흐름•표본의 장비와 통신 주체를 연결한다.

#### 한줄 요약

- 같은 트래픽도 누적 카운터는 총량, 흐름 레코드는 통신 주체, 패킷 표본은 일부 내용을 보여 준다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **정규화•상관 분석**: 서로 다른 관측 단위와 수집 시각을 공통 축으로 변환해 상태 변화와 통신 주체를 연결하는 과정이다.

</details>

- **정규화•상관 분석**은 장비 상태와 흐름•표본을 같은 인터페이스와 시각 기준으로 연결한다.

```text
에이전트•익스포터
└─ 컬렉터
   └─ 정규화•상관 분석
      └─ 시각화•경보
```

선의 의미: 장비의 에이전트•익스포터와 중앙 컬렉터, 정규화•상관 분석, 시각화•경보가 수집•저장•분석•표현 책임으로 분리된 정적 관측 계층이다.

| 구성요소 | 책임 |
|:---|:---|
| 에이전트•익스포터 | 상태•흐름•패킷 표본 생성 |
| 컬렉터 | 템플릿•순번•수집 시각 검증•저장 |
| 정규화•상관 분석 | 관측 단위•시간축 결합 |
| 시각화•경보 | 품질 임계치•이상 패턴 통지 |

#### 한줄 요약

- 장비가 만든 상태•흐름•표본을 컬렉터가 같은 시간축으로 맞춰 분석기에 전달한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **객체 식별자(Object Identifier, OID)**: 관리 정보 트리의 항목을 식별하는 값이다.
- **IP 흐름 정보 내보내기(Internet Protocol Flow Information Export, IPFIX)**: 표준 형식으로 흐름 레코드를 내보내는 프로토콜이다.
- **표본 흐름(Sampled Flow, sFlow)**: 패킷 표본과 인터페이스 카운터를 내보내는 기술이다.
- **SNMP 상태 조회**: 장비 관리 정보의 객체 식별자와 카운터를 주기적으로 요청하는 단계이다.
- **IPFIX•sFlow 전송**: 흐름 레코드와 패킷 표본•인터페이스 카운터를 컬렉터로 보내는 단계이다.
- **순번•템플릿 검증**: 수집 레코드의 누락•재시작•필드 해석 오류를 확인하는 단계이다.
- **정규화 데이터 전달**: 장비•인터페이스•시간 기준을 통일한 관측 데이터를 분석기에 제공하는 단계이다.

</details>

```text
반복 범위: 관측 주기마다 1~4단계

1. SNMP 상태 조회
      │
      ├─ OID•카운터 응답
      │
      ▼
2. IPFIX•sFlow 전송
      │
      ▼
3. 순번•템플릿 검증
      │
      ▼
4. 정규화 데이터 전달
      └─ 다음 관측 주기의 1단계로 반복
```

### 동작 원리

1. **SNMP 상태 조회**: **SNMP 상태 조회** 단계에서 필요한 **OID**를 주기적으로 요청한다.
2. **IPFIX•sFlow 전송**: **IPFIX•sFlow 전송** 단계에서 **IPFIX** 레코드와 **sFlow** 표본을 내보낸다.
3. **순번•템플릿 검증**: **순번•템플릿 검증** 단계에서 누락•재시작•필드 해석 오류를 식별한다.
4. **정규화 데이터 전달**: **정규화 데이터 전달** 단계에서 장비•인터페이스•시간 기준을 통일한다.

#### 한줄 요약

- 컬렉터는 레코드 순번과 형식을 먼저 검사한 뒤 같은 시각의 장비 상태와 트래픽을 연결한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **넷플로(NetFlow)**: 공통 속성의 패킷을 흐름 레코드로 집계하는 기술이다.

</details>

| 판단 기준 | SNMP | NetFlow•IPFIX | sFlow |
|:---|:---|:---|:---|
| 적용 기준 | **SNMP**는 장비 장애•용량 상태 | **NetFlow**•**IPFIX**는 트래픽 주체•경로 분석 | **sFlow**는 고속망 저부하 수집 |
| 핵심 특징 | OID 상태•누적 카운터 | 흐름별 바이트•패킷 집계 | 패킷 표본•인터페이스 카운터 |
| 한계 | 폴링 간 사건 누락 | 템플릿•수집기 부하 | 표본 오차•희소 흐름 누락 |

> 요약: 상태•흐름•표본을 결합해 원인을 분석한다.

#### 한줄 요약

- 표본 분석에서 데이터가 보이지 않아도 트래픽이 없다고 단정할 수 없다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **사건 왜곡**: 서로 다른 시점의 상태와 흐름을 같은 원인으로 연결하는 문제이다.
- **네트워크 시간 프로토콜(Network Time Protocol, NTP)**: 네트워크 장비의 시각을 동기화하는 프로토콜이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수집 시각•순번 불일치로 **사건 왜곡** | **NTP**•순번•재시작 검증 | 사건 상관 정확성 확보 |
| 고속망 전체 패킷 수집으로 장비 과부하 | **sFlow** 표본율•**IPFIX** 집계 조정 | 수집 비용 절감 |
| 표본 부재를 트래픽 없음으로 오인 | 카운터•흐름•표본 교차 확인 | 희소 흐름 오판 방지 |

#### 한줄 요약

- **SNMP**로 포트 사용량 급증 시각을 찾고 IPFIX로 대역 점유 주체를 확인한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **관측 수단 선택**: 분석 질문과 수집 비용에 따라 장비 상태•흐름 레코드•패킷 표본 수집 방식을 조합하는 기준이다.

</details>

- **관측 수단 선택**에서 장비 상태는 **SNMP**, 통신 주체는 **IPFIX**, 고속망 저부하는 **sFlow**가 핵심이다.

#### 한줄 요약

- 장비 상태와 통신 주체, 패킷 표본 중 질문에 필요한 자료를 수집 비용에 맞춰 조합해야 한다.
