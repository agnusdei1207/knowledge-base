## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM vs SOAR**: 로그 수집과 상관 분석 기반 탐지(SIEM)와 API 오케스트레이션 및 플레이북 기반 대응(SOAR).
- **Closed-Loop Security (폐루프 보안관제)**: 탐지(SIEM) $\rightarrow$ 조사/대응(SOAR) $\rightarrow$ 결과 피드백 및 룰 튜닝으로 순환하는 관제 체계.

</details>

- 정의/개념: **SIEM 탐지**와 **SOAR 대응**을 결합한 폐루프 관제
- 배경/필요성: 탐지와 대응을 따로 운영하면 경보가 사람 손을 거쳐야 조치로 이어지는 **전달 지연 비용**을 반복하므로, SIEM의 경보를 SOAR 플레이북 입력으로 직접 잇고 조치 결과를 다시 탐지 룰로 환류시켜 폐루프를 구성

#### 한줄 요약
- SIEM의 가시성·탐지와 SOAR의 자동 대응을 결합하여 탐지-조사-대응-피드백의 폐루프를 완성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Alert Contract (경보 계약)**: SIEM이 SOAR로 인시던트를 전달할 때 이벤트 ID, 공격 유형, 신뢰도, 소스/목적지 IP 등을 JSON 표준 규격으로 약정하는 인터페이스.
- **Feedback Loop (피드백 환류)**: SOAR의 대응 결과(성공 여부, 오탐 판정)를 SIEM으로 역전송하여 탐지 룰 임계치를 자동 보정하는 메커니즘.

</details>

- **탐지·대응 상호보완**: 상관 분석과 **플레이북 조치** 결합
- **경보 계약**: 인시던트를 **JSON 스키마**로 전달
- **피드백 환류**: 대응 결과로 **탐지 규칙 임계치 보정**

#### 한줄 요약
- 탐지-대응 상호보완, 표준 경보 계약 연동, 피드백 기반 룰 튜닝을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Security Actuators**: 방화벽, IPS, WAF, EDR, AD 등 SOAR의 API 호출을 받아 실제 차단/격리를 물리적으로 집행하는 보안 통제 장비들.

</details>

```text
[폐루프 보안관제]
|-- SIEM 탐지 엔진   : 로그 상관 분석
|-- 경보 인터페이스  : 표준 인시던트 전달
|-- SOAR 엔진        : 플레이북 조치
|-- 보안 통제 장비   : 차단·격리 집행
`-- 결과 환류 모듈   : 탐지 규칙 보정
```

선의 의미: 인프라 로그가 SIEM에서 상관 분석되어 생성된 인시던트가 SOAR로 전달되고 플레이북 조치 후 결과가 다시 SIEM 룰 튜닝으로 환류되는 구조

| 구성요소 | 책임 |
|:---|:---|
| SIEM 탐지 엔진 | 로그 정규화와 **상관 분석** |
| 경보 인터페이스 | 증적을 **표준 JSON**으로 전달 |
| SOAR 엔진 | 분기와 **플레이북 조치** 실행 |
| 보안 통제 장비 | 실제 **차단·격리** 집행 |
| 결과 환류 모듈 | 대응 결과로 **탐지 규칙 보정** |

#### 한줄 요약
- 경보 연동 인터페이스가 두 플랫폼의 유일한 접점을 이루므로, 탐지 품질의 저하가 그대로 자동 조치의 오차단으로 증폭되어 전달된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **State Verification (상태 재조회)**: SOAR가 방화벽에 차단 API를 호출한 후 실제로 정책 테이블에 룰이 정상 적재되었는지 GET으로 재조회하여 확인하는 절차.

</details>

```text
이종 로그
    |
 1. 로그 정규화
    |
 2. 상관 분석·인시던트 발행
    |
 3. 표준 경보 전달
    |
 4. 플레이북 조치
    |
 5. 상태 검증·규칙 환류
    |
 탐지 규칙
```

동작 원리

1. 로그 정규화
2. 상관 분석·인시던트 발행
3. 표준 경보 전달
4. 플레이북 조치
5. 상태 검증·규칙 환류

#### 한줄 요약
- 상태 검증 결과가 탐지 룰로 되돌아가 다음 판정을 바꾸므로, 폐루프는 대응 속도를 얻는 대신 잘못된 룰이 자동 조치로 확대되는 위험을 함께 진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIEM vs SOAR**: 탐지·가시성 중심(SIEM)과 오케스트레이션·대응 자동화 중심(SOAR)의 아키텍처 비교.

</details>

| 비교 항목 | SIEM (보안 정보 및 이벤트 관리) | SOAR (보안 오케스트레이션/자동화/대응) |
|:---|:---|:---|
| 핵심 목적 | 가시성·**위협 탐지** | **대응 자동화**·조치 |
| 주요 입력 데이터 | **원시 로그** | 정제된 **보안 경보** |
| 핵심 기술 | 정규화·상관 분석·**UEBA** | API·플레이북·**멱등성** |
| 결과물 | 인시던트·대시보드 | 차단·격리·티켓 종결 |
| 단독 운영 한계 | 조치 지연 | 원시 로그 분석·저장 부재 |

#### 한줄 요약
- SIEM은 빅데이터 상관 분석을 통한 탐지 플랫폼이며, SOAR는 API 오케스트레이션을 통한 자동 대응 플랫폼이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Concentration of Privilege (권한 집중 위험)**: SOAR가 사내 모든 방화벽, AD, EDR의 마스터 API Key를 보유함에 따라 SOAR 침해 시 전사 제어권이 탈취될 수 있는 위험.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 오탐 경보 연계로 **정상 트래픽 차단** | 신뢰도 필터와 **HITL 승인** | 서비스 중단 방지 |
| API 호출 후 **차단 미반영** | 조치 후 **상태 재조회** | 보안 사각지대 제거 |
| SOAR 계정 탈취로 **권한 집중** | **최소 권한·HSM·MFA** 적용 | 플랫폼 침해 저항성 확보 |
| 경보 폭증으로 **이벤트 유실** | **Kafka 비동기 완충** | 무손실 전달과 확장성 확보 |

#### 한줄 요약
- 신뢰도 필터링으로 오차단을 방지하고, 상태 재조회로 조치 성공을 검증하며, 최소 권한으로 SOAR 계정을 보호한다.

## Ⅶ. 결론

- 위협 식별은 **SIEM**, 반복 대응은 **SOAR**, 결과는 규칙에 환류

#### 한줄 요약
- SIEM의 탐지와 SOAR의 자동 대응을 폐루프로 결합하여 고신뢰 차세대 보안관제를 실현한다.
