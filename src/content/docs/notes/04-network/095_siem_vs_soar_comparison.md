## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM (보안 정보 및 이벤트 관리)**: 수억 개의 로그를 긁어모아 퍼즐을 맞춰서 "이거 해킹이다!"라고 범인을 찾아내고 경보(알람)를 울리는 탐지(CCTV 및 두뇌) 플랫폼이다.
- **SOAR (보안 오케스트레이션/자동화/대응)**: SIEM이 띄운 경보를 받아서, 미리 짜놓은 대본(플레이북)대로 로봇처럼 방화벽을 차단하고 PC를 팩트로 격리하는 행동 대장(팔과 다리) 플랫폼이다.

</details>

- 정의: 탐지를 담당하는 **SIEM**과 자동 조치를 담당하는 **SOAR**를 결합하여, 위협 식별부터 대응, 결과 피드백까지 완결짓는 **폐루프 보안 관제 구조(Closed-loop Framework)** 다.
- 배경: SIEM이 아무리 해킹을 기가 막히게 찾아내도, 결국 관제 요원이 수동으로 장비마다 접속해서 차단하다 보니 **대응 지연(Delay)이 발생해 골든타임을 다 날려 먹었다.**

#### 한줄 요약

- 머리(SIEM)가 해커를 찾아내면, 손발(SOAR)이 빛의 속도로 달려가서 두들겨 패고 결과를 보고하는 완벽한 콤비 플레이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **폐루프 관제 구조 (Closed-loop)**: SIEM이 찾고 $\to$ SOAR가 때려잡고 $\to$ 그 조치 결과를 다시 SIEM한테 피드백해 줘서 다음번 오탐을 줄이는 무한 성장형 팩트 사이클이다.
- **결과 환류 (Feedback Loop)**: SOAR가 실제 타격해 보니 "이거 정상 손님이었잖아!" 하면, 이 증거를 SIEM에 넘겨서 오탐 룰을 깎게 만드는 피드백 과정이다.

</details>

- **탐지의 눈과 뇌 (SIEM)**: 이종 로그를 팩트로 정규화하고 상관분석해 신뢰도 높은 근거 경보를 생성한다.
- **대응의 팔과 다리 (SOAR)**: SIEM이 넘겨준 경보에 살(위협 평판 등)을 붙이고, 플레이북을 가동해 팩트 조치를 자동 및 승인 실행한다.
- **무한 진화 사이클 (결과 환류)**: 대응 결과를 단절시키지 않고 **폐루프 관제**를 통해 다음번 탐지 룰과 대응 절차를 스스로 고도화한다.

#### 한줄 요약

- 찾는 놈(SIEM), 때리는 놈(SOAR), 맞고 나서 피드백(환류)하는 체계가 하나로 맞물려 돌아가는 생태계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **경보 계약 (Alert Contract)**: SIEM과 SOAR는 제조사가 서로 다를 수 있으므로, 둘이 대화할 때 "사건 ID, 공격자 IP, 위험도, 근거 로그"를 무조건 포함하라고 팩트로 정해놓은 인터페이스 규격서다.

</details>

```text
[ SIEM (탐지) ↔ SOAR (대응) 폐루프 팩트 결합 구조 ]

[ 수만 대의 방화벽 / 서버 / PC (로그 발생원) ]
      │ (1. 이종 로그 미친 듯이 쏟아짐)
      ▼
[ SIEM 탐지부 (Brain) ] ── (2. 상관분석 돌려서 해커 찾아냄)
      │
      ▼ (3. 경보 계약: 팩트 근거를 표준 규격으로 묶어서 토스)
[ SOAR 대응부 (Muscle) ] ── (4. 플레이북 가동. 위험도 따라 승인받고 자동 차단)
      │
      ▼ (5. 보안 장비에 API 쏴서 실제 타격)
[ 보안 통제 도구 (방화벽/백신) ]
      │
      └─▶ (6. 결과 환류: "차단 성공!" $\to$ SIEM에 알려줘서 룰 개선)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **SIEM 탐지부** | 수억 개 로그 엮어서 **"누가, 언제, 어딜 뚫었다" 팩트 경보 띄우는 눈** | Detection Engine |
| **경보 계약** | SIEM이랑 SOAR가 짝짜꿍할 때 **증거랑 자산 정보 안 빠지게 만든 규격서** | Alert Contract |
| **SOAR 대응부** | 대본(플레이북)대로 **사람 대신 조사하고 몽둥이질하는 행동 대장** | Response Engine |
| **보안 통제 도구** | SOAR의 팩트 지시를 받고 **실제로 계정 잠그고 IP 자르는 장비들** | Control Tools |
| **대응 결과 환류부** | 타격 성공/실패 팩트를 **SIEM에 피드백해서 오탐 룰을 깎게 만듦** | Feedback Loop |

#### 한줄 요약

- SIEM이 분석해서 넘기면 $\to$ SOAR가 때리고 $\to$ 그 결과가 다시 SIEM의 머리를 똑똑하게 만든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **대상 상태 재조회**: SOAR가 방화벽에 "IP 차단해" 하고 명령을 쐈는데, 실제로 차단 룰이 들어갔는지 한 번 더 API로 찔러봐서 팩트 체크하는 꼼꼼함이다.

</details>

```text
[ SIEM-SOAR 연계 지능형 자동 대응 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [원본 로그 수집 및 SIEM 정규화/분석]
│ (SIEM: 로그 싹 긁어서 퍼즐 맞춰보니 해킹이네? 알람 울려!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [경보 계약 전달 (SIEM $\to$ SOAR)]
│ (SOAR한테 사건ID, 공격 IP, 팩트 증거를 규격 맞춰서 토스함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [플레이북 가동 및 조치 승인 분기]
│ (SOAR: 위험도 크네? 요원한테 승인 버튼 팝업 띄워. 결재 완료!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [보안 도구 조치 요청 (실제 타격)]
│ (SOAR: 통역 어댑터 거쳐서 방화벽에 API 쏴서 즉각 컷트)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [대상 상태 재조회 및 결과 환류]
│ (실제로 차단됐는지 팩트 체크하고, 그 결과를 SIEM 룰에 피드백함)
└──────────────────────────────┘
```

### 동작 원리

1. 원본 로그 수집: 수만 대 장비에서 쏟아지는 로그를 SIEM이 쓸어 담고 퍼즐 맞춤.
2. 경보 계약 전달: 해킹이 확실해지면, 증거를 예쁘게 포장해서 SOAR한테 팩트로 넘겨줌.
3. 승인 분기: SOAR가 판단해서 단순 공격은 지가 컷트하고, 위험한 건 사람 승인받음.
4. 조치 실행: 방화벽이나 백신에 팩트 차단 명령(API)을 쏴버림.
5. 재조회 및 환류: 차단 똑바로 먹었는지 확인하고, 찐 해킹인지 오탐이었는지 SIEM에 돌려줌.

#### 한줄 요약

- 잡았다 $\to$ 증거 넘김 $\to$ 결재받음 $\to$ 몽둥이질 $\to$ 확인 및 피드백 순서로 흘러간다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

| 구분 | **SIEM (보안 정보/이벤트 관리)** | **SOAR (보안 오케스트레이션/대응)** |
|:---|:---|:---|
| 팩트 폭행 비유 | **CCTV 돌려보며 범인 찾는 '형사' (두뇌)** | **명령받고 문 부수고 들어가는 '기동대' (근육)** |
| 주력 임무 | 빅데이터 로그 수집, 정규화, **상관분석, 위협 탐지 및 경보 발생** | 이종 장비 연동, 조사 보강, **플레이북 기반 대응 팩트 자동화(조치)** |
| 핵심 기술 요소 | Parsing 정규화, Rule/Behavior 분석 엔진, 위험 점수 산정 | Orchestration(API 연동), Playbook(대본), Idempotency(중복 차단 방지) |
| 인간 개입 시점 | 수만 개 알람 중 찐 공격인지 오탐인지 룰 깎을 때 개입 | 자동화 처리 불가능한 고위험/대형 조치 '승인' 버튼 누를 때 개입 |
| 치명적 한계 | 범인은 기가 막히게 찾는데, **잡으러 가는 건 사람 손 타서 개느림** | SOAR 혼자선 범인 못 찾음. **SIEM이 엉뚱한 놈 찍어주면 애먼 사람(팀킬) 잡음** |

#### 한줄 요약

- SIEM 없는 SOAR는 눈먼 암살자고, SOAR 없는 SIEM은 팔다리 잘린 훈수꾼이다. 둘은 세트다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **권한 집중 (Concentration of Privilege)**: SOAR한테 방화벽 차단 권한, 메일 삭제 권한, 서버 셧다운 권한 다 몰아주면 팩트 편하겠지만, 해커가 SOAR를 털어버리면 회사망 전체가 0.1초 만에 공중분해 되는 양날의 검이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| SIEM이 싼 똥(오탐)을 **SOAR가 팩트체크 없이 차단해버림** | SIEM이 넘긴 경보에 오탐이 섞여 있는데, SOAR가 무지성 '완전 자동'으로 타격함 | 경보 넘어올 때 **'신뢰도(Confidence)' 필드 강제하고, 신뢰도 낮으면 승인 관문 태움** | SIEM 오탐이 대형 IT 서비스 중단 사고(팀킬)로 번지는 연쇄 작용 원천 컷트 |
| SOAR가 차단 명령 쐈는데 **네트워크 렉으로 실제론 차단이 안 됨** | 방화벽 네트워크 렉이나 장비 에러로 API 명령이 씹히는 팩트 미조치 현상 | 조치 쏘고 끝나는 게 아니라, 팩트 체크를 위해 **'대상 상태 재조회' 로직을 플레이북에 박음** | 쏜 명령이 100% 적용됐는지 검증하여 구멍 뚫린 보안 홀(Hole) 방어 |
| 해커가 **SOAR 플랫폼의 최고 관리자 계정을 털어버림** | SOAR 하나에 사내 모든 보안 장비를 껐다 킬 수 있는 '권한 집중'이 발생함 | SOAR 연동 계정은 **최소 권한 원칙(Least Privilege) 지키고, 핵심 조치는 다중 인증(MFA) 검** | 최상위 권한 탈취로 인한 회사 사내망 전체 초토화 위협 원천 봉쇄 |

#### 한줄 요약

- SIEM 맹신하지 말고 승인 태우고, 조치 쏜 다음엔 진짜 먹혔는지 확인하고, SOAR 계정은 목숨 걸고 지켜라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 보안 관제의 사각지대와 골든타임 누수를 완벽히 방어하기 위해, **SIEM의 상관분석 팩트 탐지**와 **SOAR의 플레이북 기반 로봇 대응**을 융합한 폐루프(Closed-loop) 지능형 보안 체계 기조 확립함

#### 한줄 요약

- SIEM과 SOAR는 단순히 두 솔루션을 이어 붙이는 게 아니다. 알람이 울리면 로봇이 패고, 스스로 진화하는 하나의 거대한 유기체를 만드는 거다.
