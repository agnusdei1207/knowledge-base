## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **HDLC(High-Level Data Link Control)**: 동기식 직렬 점대점(Point-to-Point) 및 다중점(Multipoint) 링크 상에서 신뢰성 있는 데이터 전송을 위해 ISO(ISO 13239)가 표준화한 비트 지향(Bit-Oriented) 데이터 링크 계층 프로토콜.
- **비트 지향 프로토콜(Bit-Oriented Protocol)**: 특정 문자 코드 체계(ASCII/EBCDIC)에 구애받지 않고, 임의의 이진 비트 스트림을 플래그(Flag: `01111110`) 패턴으로 프레임화하여 전송하는 프로토콜.

</details>

- 정의/개념: 물리 계층의 원시 비트 스트림을 고유 플래그(`01111110`)와 **비트 채움(Bit Stuffing)** 기법으로 프레임 단위로 동기화하고, 슬라이딩 윈도우 기반 **흐름 제어(Flow Control)** 및 CRC 기반 **오류 제어(Error Control)** 를 수행하는 **ISO 표준 L2 데이터 링크 프로토콜**
- 배경/필요성: 문자 지향 프로토콜(BSC 등)의 코드 종속성과 전송 오버헤드를 극복하고, 임의의 이진 데이터(실행 파일, 압축 데이터 등)를 투명하게 전송하며 전이중(Full-Duplex) 고속 통신을 지원할 요구

#### 한줄 요약
- 플래그와 비트 채움으로 프레임을 동기화하고 I/S/U 프레임을 통해 신뢰성 있는 링크 전송을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비트 채움(Bit Stuffing, Zero-Bit Insertion)**: 사용자 페이로드 내에 우연히 플래그 패턴(`01111110`)과 동일한 1이 6개 연속 발생하는 것을 방지하기 위해, 송신단에서 연속된 5개의 '1' 뒤에 무조건 '0'을 강제 삽입하고 수신단에서 이를 자동 제거하는 투명성(Transparency) 보장 기법.
- **피기배킹(Piggybacking)**: 수신한 데이터에 대한 확인 응답(ACK/수신 번호 $N(R)$)을 별도의 제어 프레임으로 보내지 않고, 상대방에게 전송할 정보(I-Frame) 프레임의 헤더에 함께 실어 보내는 고효율 전송 기법.

</details>

- **데이터 투명성(Data Transparency) 보장**: 비트 스터핑을 통해 페이로드 내용과 무관하게 프레임 경계(시작/종료 플래그)를 오탐 없이 식별
- **다양한 링크 토폴로지 수용**: 점대점(Point-to-Point), 점대다(Point-to-Multipoint), 루프(Loop) 토폴로지 및 반이중/전이중 모드 지원
- **체계적인 3가지 프레임 유형화**: 순수 사용자 데이터 전송(I-프레임), 흐름 및 오류 제어(S-프레임), 링크 초기화 및 모드 설정(U-프레임)으로 분리

#### 한줄 요약
- 비트 스터핑 투명성, I/S/U 프레임 분리 제어, 피기배킹을 통한 대역폭 최적화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어부(Control Field)**: 프레임의 유형(I/S/U)을 구분하고, 송신 순서 번호 $N(S)$, 수신 확인 번호 $N(R)$, 폴링/파이널(P/F) 비트를 포함하여 흐름 제어를 집행하는 핵심 필드.
- **FCS(Frame Check Sequence)**: 프레임 전송 중 비트 반전 오류를 검출하기 위해 생성 다항식(CRC-CCITT / CRC-16/32)을 적용한 16비트 또는 32비트 검사 필드.

</details>

```text
┌──────────────┬──────────────┬──────────────┬────────────────────────┬──────────────┬──────────────┐
│  Flag (8bit) │Address (8bit)│Control (8bit)│ Information (가변 길이)│  FCS (16bit) │  Flag (8bit) │
├──────────────┼──────────────┼──────────────┼────────────────────────┼──────────────┼──────────────┤
│   01111110   │  국 식별 주소 │ 프레임 제어  │ 실제 사용자 데이터 페이로드│   CRC 검사   │   01111110   │
└──────────────┴──────────────┴──────────────┴────────────────────────┴──────────────┴──────────────┘
```

선의 의미: 시작 플래그부터 종료 플래그까지 고정된 필드 배열을 통해 주소, 제어, 정보 페이로드, FCS를 엄격히 캡슐화하는 HDLC 표준 프레임 포맷

| 구성요소 | 비트 크기 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|:---|
| **Flag (플래그)** | 8 bits (`01111110`) | 프레임의 시작과 종료 경계를 명확히 동기화 | 비트 채움 적용 대상 |
| **Address (주소부)** | 8 bits (확장 가능) | 복합 다중점 링크에서 종국(Secondary Station)의 식별 주소 지정 | 방송 주소: `11111111` |
| **Control (제어부)** | 8 bits / 16 bits | I, S, U 프레임 판별 및 송수신 순서 번호($N(S), N(R)$) 탑재 | 통신 제어 핵심 |
| **Information (정보부)**| 가변 길이 | 상위 네트워크 계층(L3 IP 패킷 등)에서 전달된 순수 데이터 | I-프레임에만 존재 |
| **FCS (프레임 검사)** | 16 bits / 32 bits | CRC 다항식을 통해 전송 선로 상의 비트 오류 무결성 검증 | CRC-CCITT |

#### 한줄 요약
- Flag, Address, Control, Information, FCS 필드로 구성되어 데이터 전송과 오류 검출을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **I-프레임 / S-프레임 / U-프레임**:
  - **I-Frame(Information)**: 사용자 데이터 전송 및 $N(S), N(R)$을 통한 피기배킹 수행.
  - **S-Frame(Supervisory)**: RR(수신 준비 완료/ACK), RNR(수신 불능), REJ(거부/Go-Back-N 재전송), SREJ(선택적 재전송).
  - **U-Frame(Unnumbered)**: SABM(비동기 균형 모드 수립), DISC(링크 해제), UA(수락 응답) 등 무번호 링크 제어.

</details>

```text
1. 통신 개시: 주국 또는 대등국이 U-프레임(SABM/SNRM)을 전송하여 링크 수립 및 모드 설정
            │
            ▼
2. 상대국이 U-프레임(UA: Unnumbered Acknowledgment)을 회신 ➔ 링크 초기화 완료
            │
            ▼
3. 송신단이 사용자 데이터에 비트 스터핑을 적용하고 FCS를 계산하여 I-프레임($N(S)=0$) 전송
            │
            ▼
4. 수신단이 플래그 분리 및 비트 디스터핑(0 제거) 후 FCS(CRC) 무결성 검증 수행
            │
            ├─ [FCS 정상] ➔ S-프레임 RR($N(R)=1$) 회신 (정상 ACK)
            ▼
5. [FCS 오류] ➔ S-프레임 REJ($N(R)=0$) 회신 ➔ 송신단이 0번 프레임부터 Go-Back-N 재전송
```

**동작 원리**

1. **링크 활성화**: U-프레임을 통해 송수신 양단의 시퀀스 번호 카운터를 0으로 동기화
2. **비트 채움 송출**: 데이터 내 5연속 '1' 발생 시 하드웨어 레벨에서 '0'을 삽입하여 송출
3. **수신 디스터핑**: 수신기가 5연속 '1' 뒤에 오는 '0'을 자동으로 폐기하여 원래 비트열 복원
4. **오류 판정**: 수신 데이터에 CRC 다항식을 적용하여 나머지가 0이 아니면 즉시 폐기
5. **ARQ 재전송**: REJ(Go-Back-N) 또는 타임아웃 만료 시 해당 프레임 번호부터 일괄 재전송

#### 한줄 요약
- U-프레임 링크 수립, 비트 채움 I-프레임 전송, 수신 디스터핑, FCS 검증, S-프레임 피드백 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **동작 모드(NRM, ARM, ABM)**: 주국/종국 간 통제 권한에 따른 3가지 운영 모드.

</details>

| 비교 항목 | 정규 응답 모드 (NRM) | 비동기 응답 모드 (ARM) | 비동기 균형 모드 (ABM) |
|:---|:---|:---|:---|
| **국(Station) 구조** | **주국(Primary) - 종국(Secondary)** | **주국(Primary) - 종국(Secondary)** | **복합국(Combined) - 복합국 (대등 관계)** |
| **링크 제어 권한** | **주국이 완전 통제 (폴링/선택)** | 주국이 통제하나 종국 자발 전송 허용 | **양단이 완전 대등하게 독립적 제어** |
| **종국 전송 권한** | **주국의 폴링(Poll) 허가 시에만 전송**| 허가 없이 자발적 전송 개시 가능 | **언제든지 양방향 전이중(Full-Duplex) 전송** |
| **적용 토폴로지** | 점대다(Point-to-Multipoint) 메인프레임 | 점대다 특수 환경 | **점대점(Point-to-Point) 전용선 링크** |
| **대표 활용 사례** | IBM SNA / SDLC 단말 통신 | 구형 멀티드롭 센서망 | **X.25 (LAPB), ISDN (LAPD), PPP** |

#### 한줄 요약
- NRM은 주국 허가 기반, ARM은 종국 자발 전송 기반, ABM은 대등한 1:1 전이중 통신 모드이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **순서 번호 랩어라운드(Sequence Number Wrap-Around)**: 슬라이딩 윈도우 크기가 순서 번호 공간($2^k$)보다 크거나 같을 때 이전 프레임과 신규 프레임의 시퀀스 번호가 중복 식별되는 논리적 오류.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 페이로드 내 `01111110` 우연 발생 시 조기 프레임 종료 오인식 | 송신단 **비트 채움(Bit Stuffing: 5개 '1' 뒤 '0' 삽입)** 의무화 | 프레임 경계 오탐 방지 및 100% 데이터 투명성 확보 |
| 송수신 장비 간 동작 모드(NRM vs ABM) 불일치로 인한 링크 수립 불가 | 초기화 시 **U-프레임(SABM/SNRM) 교환을 통한 모드 자동 협상** | 이종 모드 충돌 방지 및 정상 데이터 링크 개통 보증 |
| 고속 고지연 링크에서 3비트 제어 필드($N \le 7$) 순서 번호 고갈 및 지연 | **확장 제어 필드(Extended Control Field: 7비트 $N \le 127$)** 적용 | 슬라이딩 윈도우 대형화로 링크 대역폭 파이프라인 활용률 극대화 |

#### 한줄 요약
- 비트 채움으로 경계 투명성을 확보하고, U-프레임으로 모드를 동기화하며, 확장 제어 필드로 윈도우를 최적화한다.

## Ⅶ. 결론

- **HDLC**는 비트 지향 프레임 구조와 비트 스터핑, 슬라이딩 윈도우 ARQ를 통해 현대 컴퓨터 네트워크 데이터 링크 계층의 이론적 기반을 확립한 핵심 프로토콜이며, 이후 **X.25의 LAPB**, **ISDN의 LAPD**, **인터넷의 PPP(Point-to-Point Protocol)** 및 **이더넷 프레이밍** 기술의 직접적인 모태로 계승·발전

#### 한줄 요약
- HDLC의 비트 스터핑과 프레임 제어 구조는 현대 WAN/LAN 데이터 링크 프로토콜의 표준 기반이 되었다.
