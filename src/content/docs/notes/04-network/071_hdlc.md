## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **HDLC (High-Level Data Link Control)**: 동기식 직렬 링크 상에서 신뢰성 있는 프레임 전송을 수행하는 ISO 표준(ISO 13239) 비트 지향 데이터 링크 프로토콜.
- **Bit-Oriented Protocol**: 특정 문자셋에 구애받지 않고 임의의 이진 비트열을 플래그(`01111110`)로 프레임화하여 전송하는 프로토콜.

</details>

- 정의/개념: 고유 플래그(`01111110`)와 **비트 채움(Bit Stuffing)으로 데이터 투명성을 보장하고 슬라이딩 윈도우 및 CRC 제어를 수행하는 ISO 표준 L2 프로토콜**
- 배경/필요성: 문자 지향 프로토콜(BSC)의 특정 문자셋 종속으로 인한 **임의의 이진 데이터 투명 전송 불가, 반이중 전송 비효율 및 유연한 오류 복구 한계**

#### 한줄 요약
- 비트 스터핑 투명성, I/S/U 프레임 분리 제어, 피기배킹을 통한 대역폭 최적화를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Bit Stuffing (비트 스터핑)**: 데이터 페이로드 내에 연속된 5개의 '1'이 발생하면 하드웨어가 자동으로 '0'을 삽입하여 플래그 오인식을 방지하는 기법.
- **Piggybacking (피기배킹)**: 수신 확인(ACK)을 전송할 때 별도의 ACK 프레임을 보내지 않고 전송할 데이터(I-Frame) 헤더의 $N(R)$ 필드에 얹어 보내는 기법.

</details>

- **완벽한 데이터 투명성(Bit Stuffing)**: 5연속 '1' 발생 시 **'0'을 강제 삽입하여 플래그(`01111110`) 오인식 원천 방지**
- **I/S/U 프레임 다중 제어 체계**: 정보 전송(I), 감시 및 흐름 제어(S), 링크 수립 및 무번호 제어(U) 분리
- **피기배킹(Piggybacking) 기반 고효율 전송**: 데이터 프레임 전송 시 **수신 확인 번호 $N(R)$을 함께 실어 대역폭 절감**

#### 한줄 요약
- 비트 스터핑 투명성, I/S/U 프레임 분리 제어, 피기배킹을 통한 대역폭 최적화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Control Field (제어부)**: 프레임 유형(I/S/U)을 구분하고 순서 번호 $N(S)$, $N(R)$, P/F 비트를 탑재하여 흐름 제어를 집행하는 8/16비트 필드.
- **FCS (Frame Check Sequence)**: CRC-16/32 다항식으로 선로 상의 비트 반전 오류를 검출하는 검사 필드.

</details>

```text
[HDLC 프레임 구성]
|-- Flag
|-- Address
|-- Control
|-- Information
`-- FCS
```

선의 의미: 시작 플래그부터 종료 플래그까지 고정된 필드 배열을 통해 주소, 제어, 정보 페이로드, FCS를 엄격히 캡슐화하는 구조

| 구성요소 | 비트 크기 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **Flag (플래그)** | 8 bits (`01111110`) | **프레임의 시작과 종료 경계를 명확히 동기화** | 비트 채움 대상 |
| **Address (주소부)** | 8 bits (확장 가능) | **다중점 링크에서 종국(Secondary)의 식별 주소 지정** | 방송: `11111111` |
| **Control (제어부)** | 8 bits / 16 bits | **I, S, U 프레임 판별 및 송수신 순서 번호($N(S), N(R)$) 탑재** | 흐름 제어 핵심 |
| **Information (정보부)**| 가변 길이 | **상위 네트워크 계층에서 전달된 순수 데이터 페이로드** | I-프레임 전용 |
| **FCS (프레임 검사)** | 16 bits / 32 bits | **CRC 다항식을 통해 전송 선로 비트 오류 무결성 검증** | CRC-CCITT |

#### 한줄 요약
- Flag, Address, Control, Information, FCS 필드로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **I-Frame vs S-Frame vs U-Frame**: 정보 전송(I), 감시/ACK/재전송(S), 링크 수립/해제(U).

</details>

```text
HDLC 링크 수립, 데이터 전송 및 ARQ 재전송 파이프라인
        │
   1. [U-프레임 링크 수립] 송신국이 U-프레임(SABM)을 전송하고 수신국이 UA 응답 회신
        │
   2. [비트 채움 I-프레임 송출] 데이터에 비트 스터핑(5연속 '1' 뒤 '0' 삽입) 적용 및 I-프레임 송신
        │
   3. [수신단 디스터핑 및 검증] 5연속 '1' 뒤 '0' 제거 후 FCS(CRC) 무결성 검증 수행
        │
   4. [FCS 판정] CRC 계산값과 수신 FCS 비교
   ├─ 정상: S-프레임 RR 회신 및 윈도우 전진
   `─ 오류: S-프레임 REJ 회신 및 Go-Back-N 재전송
```

#### 한줄 요약
- U-프레임 링크 수립 → 비트 채움 I-프레임 송출 → 수신단 디스터핑 및 검증 → FCS 판정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **NRM vs ARM vs ABM**: 주국 완전 통제(NRM), 종국 자발 전송(ARM), 대등국 1:1 전이중 통신(ABM).

</details>

| 비교 항목 | 정규 응답 모드 (NRM) | 비동기 응답 모드 (ARM) | 비동기 균형 모드 (ABM) |
|:---|:---|:---|:---|
| **국(Station) 구조** | **주국(Primary) - 종국(Secondary)** | **주국(Primary) - 종국(Secondary)** | **복합국(Combined) - 대등 관계** |
| **링크 제어 권한** | **주국이 완전 통제 (폴링/선택)** | 주국 통제 하 종국 자발 전송 | **양단이 완전 대등하게 독립 제어** |
| **종국 전송 권한** | **주국의 폴링(Poll) 허가 시 전송** | 허가 없이 자발적 전송 가능 | **상시 양방향 전이중(Full-Duplex)** |
| **적용 토폴로지** | 점대다(Point-to-Multipoint) | 점대다 특수 환경 | **점대점(Point-to-Point) 전용선** |
| **대표 활용 사례** | IBM SNA / SDLC 단말 통신 | 구형 멀티드롭 센서망 | **X.25 (LAPB), ISDN (LAPD), PPP** |

#### 한줄 요약
- NRM은 주국 허가 기반, ARM은 종국 자발 전송 기반, ABM은 대등한 1:1 전이중 통신 모드이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Extended Control Field**: 고속·고지연 위성 전용선에서 3비트 순서 번호($0\sim 7$)의 조기 소진을 방지하기 위해 7비트 순서 번호($0\sim 127$)로 확장하는 규격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 페이로드 내 `01111110` 우연 발생 시 조기 종료 오인식 | 송신단 **`비트 채움(Bit Stuffing: 5연속 '1' 뒤 '0' 삽입)` 의무화** | 프레임 경계 오탐 방지 및 데이터 투명성 확보 |
| 송수신 장비 간 동작 모드(NRM vs ABM) 불일치로 링크 수립 불가 | 초기화 시 **`U-프레임(SABM/SNRM) 교환`을 통한 모드 자동 협상** | 이종 모드 충돌 방지 및 정상 데이터 링크 개통 |
| 고속 고지연 링크에서 3비트 제어 필드 순서 번호 고갈 및 지연 | **`확장 제어 필드(Extended Control Field: 7비트 N(S)/N(R))`** 적용 | 슬라이딩 윈도우 확대로 링크 대역폭 활용률 극대화 |
| 잡음이 심한 선로에서 REJ로 인한 불필요한 전체 프레임 재전송 | **`선택적 거부(SREJ: Selective Reject) ARQ` 모드 활성화** | 손실된 특정 프레임만 단독 재전송하여 전송 효율 보존 |

#### 한줄 요약
- Bit Stuffing, U-프레임 협상, 확장 제어 필드, SREJ 모드로 최적화한다.

## Ⅶ. 결론

- 점대다 주국 제어는 **NRM**, 대등 점대점 전이중은 **ABM** 선택

#### 한줄 요약
- HDLC는 비트 스터핑과 I/S/U 제어 체계를 통해 현대 WAN 데이터 링크 계층 프로토콜의 표준 기반을 확립하였다.
