## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **전기전자공학자협회(Institute of Electrical and Electronics Engineers, IEEE) 802.1X**: 확장 가능 인증 프로토콜 결과에 따라 네트워크 통제 포트의 접근 권한을 부여하는 포트 기반 접근 제어 표준이다.
- **확장 가능 인증 프로토콜(Extensible Authentication Protocol, EAP)**: 여러 인증 방식을 공통 요청•응답 구조로 운반하는 인증 프레임워크이다.
- **통제 포트 접근 권한**: 인증 결과에 따라 일반 데이터 통신을 허용하거나 차단하는 논리 포트 권한이다.
- **개별 통제 한계**: 물리 접속이나 공유 암호만으로 사용자•단말별 자격과 권한을 구분하기 어려운 문제이다.

</details>

- 정의/개념: **EAP** 인증 결과로 **통제 포트 접근 권한**을 부여하는 **IEEE 802.1X** 기반 접근 제어이다.
- 배경/필요성: 물리 접속•공유 암호에는 **개별 통제 한계**가 있다.

#### 한줄 요약

- 신분 확인이 끝난 뒤 네트워크 문을 연다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인증 요청자(Supplicant)**: 단말에서 EAP 자격과 응답을 제시하는 주체이다.
- **인증 중계자(Authenticator)**: 접속 장비에서 EAP 대화를 중계하고 포트 정책을 집행하는 주체이다.
- **인증 서버(Authentication Server)**: 자격을 검증하고 네트워크 접근 권한을 결정하는 서버이다.
- **근거리망 기반 EAP(EAP over LAN, EAPOL)**: 단말과 접속 장비 사이에서 EAP 메시지를 운반하는 방식이다.
- **원격 인증 전화접속 사용자 서비스(Remote Authentication Dial-In User Service, RADIUS)**: 접속 장비와 인증 서버 사이에서 인증•권한 정보를 교환하는 프로토콜이다.
- **동적 권한**: 인증 결과에 따라 VLAN•ACL 등 단말의 네트워크 접근 정책을 접속 시점에 적용하는 권한이다.
- **가상 근거리 통신망(Virtual Local Area Network, VLAN)**: 하나의 물리 망을 논리적 접근 구역으로 분리하는 기술이다.
- **접근 제어 목록(Access Control List, ACL)**: 주소•포트•프로토콜 조건에 따라 통신을 허용하거나 차단하는 규칙 목록이다.

</details>

- **인증 요청자**•**인증 중계자**•**인증 서버** 간 인증•집행 역할을 분리한다.
- **EAPOL**•**RADIUS**로 단말 EAP 인증 대화를 중계한다.
- **통제 포트**•**동적 권한**으로 승인 후 **VLAN**•**ACL**을 적용한다.

#### 한줄 요약

- 스위치는 인증 대화를 전달하고 결과를 집행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **EAPOL 중계**: 단말의 EAP 요청•응답을 접속 장비가 수신하는 중계이다.
- **RADIUS 중계**: 접속 장비가 EAP 대화와 권한 정보를 인증 서버와 교환하는 중계이다.
- **통제 포트**: 인증 결과에 따라 일반 데이터 통신의 허용 여부가 바뀌는 논리 포트이다.
- **신원 저장소**: 사용자•단말 계정과 인증 자격 정보를 제공하는 저장소이다.
- **인증서 저장소**: 인증기관과 인증서 신뢰•폐기 정보를 제공하는 저장소이다.

</details>

```text
802.1X EAP 인증 구조
├─ 인증 요청자
├─ 인증 중계자
├─ 인증 서버
├─ 신원 저장소
├─ 인증서 저장소
└─ 통제 포트
```

가지의 의미: 자격 제시•중계•검증•신뢰•집행 책임을 분리한 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 인증 요청자 | **인증 요청자**가 자격•EAP 응답 제시 |
| 인증 중계자 | **인증 중계자**가 인증 중계•포트 상태 집행 |
| 인증 서버 | **인증 서버**가 자격 검증•권한 결정 |
| 신원 저장소 | **신원 저장소**가 계정•인증 자격 정보 제공 |
| 인증서 저장소 | **인증서 저장소**가 인증기관•신뢰•폐기 정보 제공 |
| 통제 포트 | **통제 포트**가 승인 후 일반 데이터 허용 |

#### 한줄 요약

- 인증 서버의 판단을 접속 장비가 포트에 적용한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **신뢰 체인 검증**: 인증서 서명을 신뢰 저장소의 인증기관까지 확인해 상대 신원의 유효성을 판정하는 과정이다.
- **전송 계층 보안 기반 EAP(EAP-Transport Layer Security, EAP-TLS)**: 단말과 인증 서버가 인증서로 상호 신원을 검증하는 EAP 방식이다.
- **RADIUS EAP 대화 중계**: 중계자가 EAP 요청•응답을 RADIUS로 인증 서버에 제공하는 단계이다.
- **인증서•신뢰 체인 검증**: 단말•서버 인증서와 신뢰점을 대조해 유효성을 확인하는 단계이다.
- **권한 정책 전달**: 인증 서버가 승인 여부와 망 정책을 중계자에게 제공하는 단계이다.
- **통제 포트 정책 적용**: 중계자가 승인 구역과 VLAN•ACL을 논리 포트에 설정하는 단계이다.

</details>

```text
EAPOL 접속 요청
        │
        ▼
1. RADIUS EAP 대화 중계
        │
        ▼
2. 인증서•신뢰 체인 검증
        │
        └── 신뢰 정보 반환
                    │
                    ▼
3. 권한 정책 전달
        ├─ 거부: 통제 포트 차단
        └─ 승인
             │
             ▼
     4. 통제 포트 정책 적용
             │
             └── 인증 결과 반환
```

### 동작 원리

1. RADIUS EAP 대화 중계: **EAPOL 중계**와 **RADIUS 중계**로 **RADIUS EAP 대화 중계**를 수행한다.
2. 인증서•신뢰 체인 검증: **신뢰 체인 검증**을 포함한 **인증서•신뢰 체인 검증**을 수행한다.
3. 권한 정책 전달: 인증 서버가 **권한 정책 전달**로 승인 여부를 제공한다.
4. 통제 포트 정책 적용: 승인 구역에 **통제 포트 정책 적용**을 수행한다.

#### 한줄 요약

- 서버의 승인 뒤에만 일반 통신이 열린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **터널형 EAP**: 서버 인증으로 보호 터널을 만든 뒤 그 안에서 계정 자격을 검증하는 EAP 방식이다.
- **매체 접근 제어 인증 우회(Media Access Control Authentication Bypass, MAB)**: 802.1X를 지원하지 않는 장비의 MAC 주소만 확인해 제한적으로 접근을 허용하는 예외 방식이다.

</details>

| 802.1X 인증 방식 | **EAP-TLS** | **터널형 EAP** | **MAB** |
|:---|:---|:---|:---|
| 적용 기준 | 관리 단말•강한 보안 | 계정 중심 기존 환경 | 인증 미지원 장비 |
| 핵심 특징 | 양쪽 인증서 상호 인증 | 보호 터널 내 계정 인증 | 단말 주소만 확인 |
| 한계 | 인증서 운영 실패 | 가짜 서버•계정 탈취 | 주소 위조•낮은 신뢰 |

> 요약: 관리 단말에는 인증서 상호 인증 우선이 핵심이다.

#### 한줄 요약

- 주소 기반 우회는 예외 장비에만 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인증서 폐기 상태**: 만료 전 신뢰가 철회된 인증서를 인증 과정에서 거부하도록 제공하는 상태 정보이다.
- **상호운용 시험**: 단말•접속 장비•RADIUS 서버가 표준 EAP와 포트 정책을 일관되게 처리하는지 검증하는 시험이다.
- **의견 요청 문서(Request for Comments, RFC)**: 인터넷 프로토콜과 운영 지침을 공개 정의하는 표준 문서 계열이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가짜 인증 서버 접속 | **RFC** 9190 상호 인증•신뢰점 | 서버 위장 차단 |
| 포트 상태의 집행 불일치 | **IEEE 802.1X**-2020 **상호운용 시험** | 인증 후 권한 일관성 |
| 인증서 만료•폐기 지연 | 자동 갱신•**인증서 폐기 상태** 확인 | 접속 장애•탈취 방지 |

#### 한줄 요약

- 단말과 서버에 신뢰점•인증서를 자동 배포하고 표준 상호운용과 만료•폐기 경로를 함께 검증한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **최소 권한 MAB**: 인증 미지원 장비에 주소 기반 예외를 적용하되 필요한 망 영역과 기간만 허용하는 통제이다.
- **주기 재인증(Periodic Reauthentication)**: 접속 중에도 정해진 주기나 상태 변화 시 자격과 권한을 다시 검증하는 절차이다.
- **802.1X 인증 방식 선택**: 단말 관리 수준•인증서 운영 가능성•표준 지원 여부에 따라 EAP-TLS•터널형 EAP•MAB를 결정하는 판단이다.

</details>

- 관리 단말은 EAP-TLS, 계정 환경은 터널형 EAP, 미지원 장비는 **최소 권한 MAB** 선택

#### 한줄 요약

- 인증 방식과 문을 여는 절차를 함께 설계한다.
