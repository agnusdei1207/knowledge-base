## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN (제어기 영역 네트워크)**: 자동차 안에 있는 수십 개의 뇌(ECU)들이 두 가닥의 구리선만으로 충돌 없이 서로 대화하게 만든 차량용 버스 통신 표준이다.
- **ECU (전자제어장치)**: 에어백 터트리고, 브레이크 잡고, 엔진 회전수 조절하는 자동차 안의 소형 컴퓨터(뇌)다.

</details>

- 정의: **CAN**은 수십 개의 **ECU**가 하나의 얇은 공유 회선에 붙어서, 메시지의 식별자(ID)로 팩트 폭행하며 누가 먼저 말할지 우선순위를 정하는 차량용 통신 규격이다.
- 배경: 자동차 부품마다 ECU끼리 1:1로 구리선을 깐다 치면, 차 안에 구리선만 몇 백 킬로미터가 들어가 차가 무거워서 안 굴러가니까, **두 가닥 선만으로 다 같이 통신(Bus)하려고 만들었다.**

#### 한줄 요약

- 자동차 안의 수많은 컴퓨터들이 얽히고설킨 전선 지옥을 없애고, 두 가닥 선으로 깔끔하게 대화하게 만든 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비파괴 중재 (Non-destructive Arbitration)**: 에어백 센서랑 에어컨 센서가 동시에 말할 때, 식별자(ID) 번호가 빠른 에어백 메시지(승자)는 그대로 살리고 에어컨(패자)은 스스로 입을 닫아버리는 똑똑한 충돌 회피 기술이다.
- **버스 오프 (Bus Off)**: 어떤 ECU가 고장 나서 자꾸 에러 메시지만 뿜어대면, 다른 놈들 통신 못 하니까 걔를 버스(통신망)에서 강제로 퇴장(격리)시켜 버리는 자가 치료 기능이다.

</details>

- **선빵 필승 (우선순위 ID 중재)**: 누가 보냈냐가 중요한 게 아니라(주소 없음), 메시지 ID 자체가 우선순위를 뜻해서 번호가 낮을수록 깡패(긴급)다.
- **입 닥쳐 기술 (비파괴 중재)**: 이더넷처럼 동시에 말해서 데이터가 깨지는 게 아니라, 짬 안 되는 놈이 조용히 입을 다물어서 긴급 메시지가 1초도 지연 없이 통과한다.
- **트롤링 강퇴 (버스 오프)**: 계속 통신 에러 내며 전체 망을 마비시키는 트롤 ECU는 에러 카운트를 꽉 채워서 통신망에서 완전히 격리해 버린다.

#### 한줄 요약

- 동시에 말해도 우선순위가 높은 놈만 살아남고, 헛소리 계속하면 아예 퇴장시켜버리는 철저한 계급 사회다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN 송수신기 (Transceiver)**: ECU의 0과 1 논리 비트를, 선 두 가닥의 전압 차이(차동 전압)로 바꿔서 버스에 실어 보내는 입이자 귀다.
- **종단 저항 (Terminating Resistor)**: 통신선 양쪽 끝에 120옴짜리 저항을 달아서, 전파가 끝에 부딪혀서 메아리(반사파) 쳐 돌아오는 걸 막아주는 댐퍼다.

</details>

```text
[ CAN 통신망 팩트 폭행 구조 ]

[ 1. ECU (전자제어장치) ] ── (브레이크 밟았다는 데이터 생산함)
      │
      ▼
[ 2. CAN 컨트롤러 / 송수신기 ] ── (데이터를 전압 차이로 바꿔서 선에 태움)
      │
========================= (3. 차동 공유 버스 - 두 가닥 구리선)
  │                   │
[종단 저항]          [종단 저항] ── (양 끝에서 전파 메아리 막아줌)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **ECU (마이컴)** | 에어백 터트릴지 말지 결정하고 **메시지 던지는 대가리** | Microcontroller |
| **CAN 송수신기** | ECU가 준 0과 1을 **물리적인 전압 차이(CAN_H, L)로 바꿔주는 입** | Transceiver |
| **차동 공유 버스** | 수십 개 ECU가 **다 같이 물고 빨며 공유하는 두 가닥짜리 꼬인 구리선** | CAN Bus |
| **종단 저항 (120Ω)** | 버스 양 끝에서 **전기 신호가 튕겨 나오는 메아리(반사파)를 흡수해 줌** | Terminator |

#### 한줄 요약

- 대가리(ECU)가 생각한 걸 입(송수신기)이 전압으로 바꿔서 구리선(버스)에 태우면 끝이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우성 비트 (Dominant Bit)**: 0(우성)과 1(열성)이 동시에 구리선에 실리면, 0이 1을 씹어먹고 선을 지배해버리는 CAN 통신의 핵심 물리 법칙이다.
- **유휴 버스 감지**: 구리선이 비어 있는지 팩트 체크하고 송신 시작 시점을 눈치 보는 단계다.

</details>

```text
[ CAN 비파괴 중재 및 전송 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [유휴 버스 감지]          │
│ (ECU들: 선 비었냐? 오케이 다 같이 말한다 실시!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [ID 비트 중재 (눈치 게임)]│
│ (A: 난 ID 001(에어백)이다! B: 난 ID 100(에어컨)인ㄷ.. 읍!)
└──────────────┬───────────────┘
               ▼ (B 패배, 조용히 입 다묾)
┌──────────────────────────────┐
│ 3. [승자의 데이터/CRC 전송]  │
│ (A: 비켜! 에어백 터진다 데이터 쫙 쏨 (에러 체크용 CRC도 첨부))
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [수신 프레임 팩트 체크]   │
│ (모든 ECU: 에어백 터진대! 에러 없이 잘 받았음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [ACK 비트 응답]           │
│ (수신자들: 잘 받았다고 ACK 비트(우성 0) 쾅 찍어줌. 전송 끝!)
└──────────────────────────────┘
```

### 동작 원리

1. 유휴 버스 감지: 회선이 비었을 때 ECU들이 동시에 튀어나와 송신을 시작한다.
2. ID 비트 중재: 서로 자기 ID를 한 비트씩 쏴서, **우성 비트(0)**를 쏜 놈이 이기고 진 놈은 바로 찌그러진다.
3. 데이터•CRC 전송: 눈치 게임 승자가 본론(데이터)과 에러 검출용 꼬리표(CRC)를 쫙 보낸다.
4. 수신 프레임 전달: 이 데이터는 구리선을 타고 모든 ECU에게 다 뿌려진다.
5. ACK 비트 응답: 에러 없이 잘 받은 놈들이 버스에 ACK 비트(0)를 덮어써 주면 송신자가 안심하고 끝낸다.

#### 한줄 요약

- 눈치 게임으로 대장(우선순위) 정하고 $\to$ 대장이 할 말 다 하고 $\to$ 쫄따구들이 잘 들었다고 대답하는 구조다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAN FD (가변 데이터율)**: 기존 클래식 CAN이 8바이트밖에 못 보내서 너무 답답하니까, 데이터 구간에서만 기어 변속(구간 가속)해서 속도를 높이고 최대 64바이트를 쏘는 업그레이드 버전이다.
- **CAN XL (초장형)**: 최대 2048바이트 데이터 필드를 지원하는 자율주행 시대의 초대용량 규격이다.

</details>

| CAN 규격 비교 | **클래식 CAN (CAN CC)** | **CAN FD (가변 속도)** | **CAN XL (초대용량)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **삐삐** (짧은 숫자만 띡 보냄) | **피처폰 SMS** (좀 더 길고 빠름) | **스마트폰 카톡** (파일도 보냄) |
| 최대 페이로드 | 최대 **8바이트** (쪼잔함) | 최대 **64바이트** | 최대 **2048바이트** |
| 핵심 특징 | 에어컨, 윈도우 조작 등 흔한 저속 제어 | 머리부터(중재) 꼬리(데이터)까지 **속도를 다르게(가속) 변속함** | 이더넷급으로 통신하는 차량용 대용량 백본망 |
| 치명적 한계 | 대역폭(1Mbps)이 너무 좁아서 자율주행에는 택도 없음 | 기존 클래식 CAN이랑 섞어 쓰려면 게이트웨이 복잡해짐 | 배선 길이랑 토폴로지 빡세게 설계 안 하면 에러 폭발함 |

#### 한줄 요약

- 옛날 차는 삐삐(CC)만으로 충분했지만, 자율주행 시대엔 피처폰(FD)과 스마트폰(XL)급 용량이 필수다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 기아 (Starvation)**: 긴급한 브레이크, 에어백(ID 낮은 놈들)이 버스를 계속 차지해 버리면, 우선순위 밀린 깜빡이, 와이퍼(ID 높은 놈들)는 계속 양보만 하다가 평생 동작을 못 하는 바보 같은 현상이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 와이퍼 켰는데 **1분 뒤에 움직임 (우선순위 기아)** | 고우선순위(에어백/엔진) 메시지가 꽉 차서, 와이퍼(저우선순위)가 버스를 평생 못 탐 | 버스 부하율 계산하고, **최악 응답 시간(Worst Case) 내에 도착하게 ID 할당 최적화함** | 덜 중요한 기능도 타임아웃 안 나고 제때 동작함 |
| 차 시동 걸었더니 **통신 에러 나면서 차가 뻗음** | 구리선이 너무 길거나 종단 저항(120옴)이 빠져서 신호가 튕기면서 파형이 씹창남 | 오실로스코프로 **종단 저항 찍어보고 토폴로지(배선 길이) 한계치 팩트 체크함** | 신호 반사 메아리 잡고 물리 계층 에러 완전 차단 |
| 침수된 에어컨 ECU가 **에러 프레임을 무한대로 뿜어냄** | 고장 난 ECU가 헛소리(에러 프레임)를 1초에 수천 번 쏴서 전체 통신망이 마비됨 | 에러 카운터 찰 때까지 기다렸다가 **스스로 강제 퇴장(버스 오프)되게 하드웨어 로직 켬** | 트롤 하나 때문에 차 전체 멈추는 대참사 방어 |

#### 한줄 요약

- 와이퍼 평생 못 움직이는 거 막으려면 ID 잘 분배하고, 양 끝에 저항 꼭 달고, 트롤짓 하는 놈은 강퇴시켜라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 자동차 내 구리선 배선 지옥을 해결하고 신뢰성 있는 제어를 위해, **비파괴 중재**와 **차동 신호**, **CAN CC/FD/XL 진화**를 결합한 차량용 버스 통신 기조 확립함

#### 한줄 요약

- CAN 통신은 차 안에 컴퓨터 수십 대를 쑤셔 넣고도 선 두 가닥으로 충돌 없이 기가 막히게 대화하게 만든 마법이다.
