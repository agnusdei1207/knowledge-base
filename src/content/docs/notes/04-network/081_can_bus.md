## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN (Controller Area Network)**: 차량 내 ECU들이 꼬임선 2선(CAN_H/CAN_L) 버스 상에서 상호 통신하는 직렬 통신 표준 (ISO 11898).
- **ECU (Electronic Control Unit)**: 엔진, 조향, 브레이크, 에어백 등을 소프트웨어 알고리즘으로 제어하는 차량용 임베디드 컴퓨터.

</details>

- 정의/개념: 차량 내 복수 ECU가 2선식 차동 버스에서 메시지 ID 기반의 비파괴 비트 단위 중재와 차동 전압으로 충돌 없이 우선순위 통신을 보장하는 차량용 직렬 네트워크(ISO 11898)
- 배경/필요성: 자동차의 급격한 전장화(Electrification)로 인해 엔진, 브레이크, 조향, 편의 장치 등 수십 개의 전자제어장치(ECU)가 탑재되는 환경에서, ECU 간 점대점(Point-to-Point) 1:1 배선 방식은 차량 와이어링 하네스(Wiring Harness)의 무게와 부피를 기하급수적으로 증가시키고 복잡한 배선에 따른 결함률 상승과 생산성 저하를 초래함에 따라, 꼬임선 2선(CAN_H/CAN_L) 버스 상에서 전 ECU가 공유하며 메시지 식별자(ID) 기반의 비파괴 비트 단위 중재(CSMA/CD+NBA)와 차동 전압 전송을 수행하는 차량용 직렬 통신 표준인 CAN 버스(ISO 11898)를 도입하여 와이어링 하네스 80% 이상 경량화, 엔진 점화 노이즈(EMI)에 대한 강력한 면역성 및 결정론적(Deterministic) 우선순위 제어 신뢰성을 달성할 필요

#### 한줄 요약
- 점대점 배선이 ECU 수의 제곱으로 늘리던 하네스 비용을 공유 버스 하나로 접고, 그 대가로 생긴 충돌 문제를 비파괴 ID 중재로 해소한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Dominant vs Recessive Bit**: 버스 상에서 전기적으로 '0'이 '1'을 덮어쓰는 우성('0') 비트와 전압 변위가 없는 열성('1') 비트.
- **Wired-AND Logic**: 여러 노드가 동시에 신호를 출력할 때 단 하나라도 '0'을 출력하면 버스 전체가 '0'으로 구동되는 하드웨어 특성.

</details>

- 비파괴 비트 단위 중재(CSMA/CR): **Wired-AND Logic** 버스에서 우성 '0'이 열성 '1'을 덮어써 낮은 ID가 우선 전송
- 차동 신호 노이즈 내성: CAN_H와 CAN_L 전압 차로 **Dominant vs Recessive Bit**를 판정
- 메시지 지향 브로드캐스팅: 노드 주소가 아닌 메시지 식별자(ID)를 기반으로 전 노드에 동시 방송 및 필터링 수신

#### 한줄 요약
- 우성 비트가 열성을 덮어쓰는 Wired-AND 물리 특성 하나가 중재·ACK·에러 프레임을 모두 떠받치므로, 상위 프로토콜이 얇아지는 대신 버스 길이와 비트율이 전파 지연에 묶인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN 컨트롤러(CAN Controller)**: 프레임 조립, 비트 스터핑, CRC 계산, 비파괴 중재 및 에러 카운터(TEC/REC)를 관리하는 디지털 칩셋.
- **종단 저항(Termination Resistor, 120Ω)**: 전송 선로의 신호 반사파 왜곡을 방지하기 위해 버스 양 끝단에 장착하는 임피던스 정합 저항 (합성 $60\Omega$).

</details>

```text
[CAN 네트워크]
  ├── [제어 계층] ───────── [CAN 컨트롤러]
  │                           │
  ├── [변환 계층] ───────── [CAN 트랜시버]
  │                           │
  └── [물리 전송선] ─────── [차동 꼬임선 버스]
        ├── [신호선] ────── [CAN_H / CAN_L]
        └── [임피던스] ──── [양단 종단 저항(120Ω)]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **CAN 컨트롤러** | 프레임·중재·CRC·오류 상태 관리 |
| CAN 트랜시버 | 논리 신호와 차동 전압 변환 |
| 차동 꼬임선 버스 | CAN_H·CAN_L 물리 신호 전달 |
| **종단 저항** | 선로 임피던스 정합과 반사 억제 |

#### 한줄 요약
- 컨트롤러가 중재와 오류 처리를 전담하고 트랜시버가 논리 레벨을 차동 전압으로 바꾸므로, 상위 소프트웨어는 버스 경합이나 전기적 잡음을 직접 다루지 않는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ACK Slot Overwrite**: 송신 노드가 열성('1')으로 비워둔 ACK 슬롯에, 정상 수신한 모든 노드가 동시에 우성('0')을 덮어써서 무결성을 확인하는 메커니즘.

</details>

```text
CAN 비파괴 비트 중재 및 프레임 송수신 파이프라인
        │
   1. [유휴 감지 및 동시 송출] 버스 유휴 상태에서 복수 ECU가 SOF(우성 '0') 동시 송출
        │
   2. [비트 단위 ID 중재] MSB부터 1비트씩 버스에 인가하고 자신의 출력과 버스 전압 대조
        │
   3. [열성 노드 패배 및 양보] 열성('1') 송출 노드가 버스의 우성('0')을 감지하고 즉시 수신 전환
        │
   4. [최우선 노드 무손실 전송] 최상위 우선순위(최소 ID) 승자 노드가 중단 없이 페이로드/CRC 전송
        │
   ▼
5. [수신단 ACK 구동] 수신 노드들이 CRC 검증 후 ACK 슬롯에 우성('0')을 인가하여 송신 성공 확정
```

분기 결과: 중재에서 진 노드는 수신자로 전환해 같은 프레임을 그대로 받아들이고, 승자 프레임의 ACK 슬롯에 정상 수신 노드가 우성을 덮어쓰는 **ACK Slot Overwrite**로 성공이 확정되므로 별도 응답 프레임 비용이 없다.

#### 한줄 요약
- ID 비트 중재에서 승자와 패자가 갈리되 프레임이 파기되지 않으므로, 충돌 재전송 비용 없이 우선순위 차이가 대기 지연으로만 환산된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Classic CAN vs CAN FD vs CAN XL**: 8B/1Mbps(CAN 2.0), 64B/5Mbps(CAN FD), 2048B/20Mbps(CAN XL).

</details>

| 비교 항목 | 클래식 CAN (CAN 2.0 / CC) | CAN FD (Flexible Data-rate) | CAN XL (Extra Long) |
|:---|:---|:---|:---|
| 페이로드 | 최대 8바이트 | 최대 64바이트 | 최대 2,048바이트 |
| 비트율 | 단일 비트율 | 데이터 구간 가속 | 데이터 구간 고속화 |
| 중재 방식 | 비트 단위 중재 | 중재 구간과 데이터 구간 분리 | 중재 구간과 데이터 구간 분리 |
| 상위 데이터 | 제한된 제어 데이터 | 더 큰 제어·센서 데이터 | 이더넷 프레임 전달 지원 |
| 적용 영역 | 차체·파워트레인 제어 | 고속 센서·제어 | 존 아키텍처 백본 후보 |

#### 한줄 요약
- CAN 2.0은 기본 차체 제어, CAN FD는 ADAS 센서 고속화, CAN XL은 SDV 대용량 백본에 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Bus-Off Isolation**: 노드가 전송 에러 카운터(TEC > 255)를 초과할 때 버스 전체 마비(Babbling Idiot)를 막기 위해 스스로 트랜시버를 전기적으로 차단하는 고장 격리 기제.
- **WCRT (Worst-Case Response Time)**: 메시지가 상위 우선순위 메시지의 간섭과 진행 중 프레임의 블로킹을 모두 겪을 때 큐잉부터 전송 완료까지 걸리는 최대 시간을 계산해 데드라인 충족 여부를 판정하는 실시간 스케줄링 해석.
- **분할 종단(Split Termination)**: 120Ω 종단 저항을 60Ω 두 개로 나누고 중간 탭을 커패시터로 접지해 공통 모드 노이즈를 흘려보내는 종단 방식.
- **SecOC (Secure Onboard Communication)**: AUTOSAR 통신 스택에서 PDU에 신선도 값(Freshness Value)과 MAC을 붙여 위변조·재전송 메시지를 수신 측이 검증하고 폐기하게 하는 보안 모듈.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고우선순위 트래픽 폭주 시 저우선순위 ECU 메시지의 전송 기아(Starvation) | **WCRT** 해석 기반 ID 설계 및 버스 부하율 70% 통제 | 모든 기능의 실시간 데드라인 보장 |
| 종단 저항 누락 또는 긴 스터브 라인으로 인한 신호 반사파 왜곡 | 양단 **분할 종단** 및 스터브 0.3m 이내 제한 | 신호 링잉 및 공통 모드 노이즈 제거 |
| 결함 노드의 연속 에러 프레임 방출로 인한 버스 전체 마비(Babbling Idiot) | CAN 컨트롤러의 **Bus-Off Isolation** 활성화 | 결함 노드의 버스 독점 차단 및 자율 복원 |
| 평문 브로드캐스팅 특성으로 인한 메시지 위변조 및 스푸핑 위협 | AUTOSAR **SecOC** MAC 인증 적용 | 비인가 제어 명령 차단 및 주행 안전 무결성 보증 |

#### 한줄 요약
- CAN 실무 대책은 공유 버스가 싸게 산 단순성의 청구서라, 스케줄 해석·종단·격리·인증을 설계 단계에 미리 지불해야 런타임 충돌 비용을 피한다.

## Ⅶ. 결론

- 지난 수십 년간 자동차 전장 아키텍처의 신경망 역할을 수행하며 차량용 임베디드 네트워크의 가장 지배적이고 신뢰성 높은 글로벌 표준(ISO 11898)으로 정립되었으며, 소프트웨어 정의 차량(SDV)과 자율주행 고도화에 맞추어 페이로드를 확장한 CAN FD(64B/5Mbps) 및 CAN XL(2048B/20Mbps)로 진화하는 가운데, 실무 전장 시스템 설계 시에는 노이즈 링잉을 방지하는 120Ω **분할 종단**(Split Termination) 배치, 저우선순위 메시지 기아를 방지하는 최악 응답 시간(**WCRT**) 기반 ID 설계 및 버스 부하율 70% 통제, 결함 노드의 버스 독점을 차단하는 Bus-Off 자동 격리, 메시지 위변조를 방지하는 AUTOSAR **SecOC** 암호화 인증을 결합하여 완벽한 차량 통신 안전성을 완성

#### 한줄 요약
- CAN 버스는 비파괴 비트 중재와 차동 신호 전송을 통해 차량 임베디드 제어의 실시간 신뢰성을 보장하는 핵심 전장 네트워크다.
