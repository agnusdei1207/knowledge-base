## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **제어기 영역 네트워크(Controller Area Network, CAN)**: 차량 ECU가 공유 회선에서 프레임 식별자로 전송 우선순위를 중재하는 차량용 버스 통신 규격이다.
- **전자제어장치(Electronic Control Unit, ECU)**: 차량의 센서 입력을 처리하고 제어 명령을 실행하는 제어기이다.

</details>

- 정의/개념: **CAN**은 여러 **ECU**가 공유 회선에서 식별자로 우선순위를 중재하는 차량용 버스 통신이다.
- 배경/필요성: 제어기별 점대점 배선은 배선량과 확장 복잡도를 키운다.

#### 한줄 요약

- 여러 차량 제어기가 한 회선을 함께 쓰면서 더 긴급한 프레임이 충돌 없이 먼저 지나가게 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비파괴 중재**: 동시 송신에서 낮은 우선순위 노드만 중단하고 승자의 프레임은 손상하지 않는 방식이다.
- **버스 오프**: 오류 카운터가 한계를 넘은 노드를 송신에서 격리해 버스 영향을 차단하는 상태이다.
- **식별자(Identifier, ID)**: CAN 프레임의 메시지 종류와 중재 우선순위를 나타내는 값이다.

</details>

- **ID**의 우성 비트를 비교해 전송 우선순위를 중재한다.
- **비파괴 중재**는 패자만 중단하고 승자 프레임을 보존한다.
- 오류가 누적된 노드는 **버스 오프** 상태로 격리한다.

#### 한줄 요약

- 동시에 말해도 우선순위가 낮은 장치만 조용히 멈추므로 긴급 메시지는 깨지지 않고 전송된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어기 영역 네트워크 송수신기(Controller Area Network Transceiver, CAN 송수신기)**: ECU의 논리 비트와 차동 버스 전압을 상호 변환하는 회로이다.
- **종단 저항**: 공유 회선 양 끝에서 신호 반사를 줄여 차동 파형을 유지하는 저항이다.

</details>

- **CAN 송수신기**가 ECU 논리 비트를 차동 전압으로 바꾸고 **종단 저항**이 회선 끝의 신호 반사를 줄인다.

```text
CAN 버스
├─ 전자제어장치
├─ CAN 송수신기
├─ 차동 공유 버스
└─ 양끝 종단 저항
```

선의 의미: 전자제어장치와 CAN 송수신기는 논리 비트•차동 전압 변환 관계이고, 차동 공유 버스는 모든 노드의 공통 프레임 전달 매체이며 양끝 종단 저항과 신호 반사 억제 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 전자제어장치 | 메시지 생성•수신 필터링 수행 |
| CAN 송수신기 | 논리 비트•차동 전압 변환 |
| 차동 공유 버스 | 모든 노드에 동일 프레임 전달 |
| 양끝 종단 저항 | 회선 끝 신호 반사 억제 |

#### 한줄 요약

- 각 ECU의 송수신기가 두 가닥 회선에 붙고 양 끝 저항이 반사를 줄여 모든 장치가 같은 프레임을 본다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우성 비트**: 열성 비트와 동시에 전송되면 버스 값을 0으로 결정해 중재 우위를 얻는 논리 비트이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: 다항식 나머지로 프레임 전송 오류를 검출하는 방식이다.
- **확인 응답(Acknowledgment, ACK)**: 하나 이상의 수신 노드가 정상 수신했음을 알리는 응답이다.
- **유휴 버스 감지**: 공유 회선이 비어 있는지 확인해 송신 시작 시점을 정하는 단계이다.
- **ID 비트 중재**: 송신 식별자와 버스 값을 비트별로 비교해 우선순위 승자를 정하는 단계이다.
- **데이터•CRC 전송**: 중재 승자가 데이터와 오류 검사값을 프레임으로 보내는 단계이다.
- **수신 프레임 전달**: 승자 프레임을 공유 버스의 모든 노드에 전파하는 단계이다.
- **ACK 비트 응답**: 정상 수신 노드가 확인 비트를 버스에 기록하는 단계이다.

</details>

```text
반복 범위: 전송 완료까지 1~5단계

1. 유휴 버스 감지
      │
      ▼
2. ID 비트 중재
      ├─ 패배: 송신 중단 후 1단계 재시도
      └─ 승리
          │
          ▼
3. 데이터•CRC 전송
          │
          ▼
4. 수신 프레임 전달
          │
          ▼
5. ACK 비트 응답
          ├─ ACK 없음•오류: 1단계 재시도
          └─ ACK 확인: 전송 완료
```

### 동작 원리

1. 유휴 버스 감지: **유휴 버스 감지** 단계에서 회선이 비었을 때 송신을 시작한다.
2. ID 비트 중재: **ID 비트 중재** 단계에서 **우성 비트**와 버스값을 비교한다.
3. 데이터•CRC 전송: **데이터•CRC 전송** 단계에서 승자가 **CRC**를 포함한 프레임을 보낸다.
4. 수신 프레임 전달: **수신 프레임 전달** 단계에서 승자 프레임을 모든 노드에 전파한다.
5. ACK 비트 응답: **ACK 비트 응답** 단계에서 정상 수신 노드가 **ACK**를 기록한다.

#### 한줄 요약

- ECU들은 ID를 한 비트씩 비교해 승자를 정하고 CRC와 ACK 결과에 따라 전송을 끝내거나 다시 시도한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **클래식 CAN(Classical CAN, CAN CC)**: 최대 8바이트 데이터 필드를 지원하는 CAN 규격이다.
- **가변 데이터율 CAN(CAN Flexible Data-Rate, CAN FD)**: 최대 64바이트와 데이터 구간 가속을 지원하는 규격이다.
- **초장형 CAN(CAN Extra Long, CAN XL)**: 최대 2048바이트 데이터 필드를 지원하는 규격이다.
- **구간 가속(Bit-Rate Switching)**: CAN FD가 중재 구간 뒤 데이터 구간의 비트율을 높여 전송 시간을 줄이는 기능이다.

</details>

| CAN 규격 | CAN CC | CAN FD | CAN XL |
|:---|:---|:---|:---|
| 적용 기준 | **CAN CC**는 소량•주기 제어 메시지 | **CAN FD**는 중용량•고속 차량 데이터 | **CAN XL**은 대용량•고속 백본 연계 |
| 핵심 특징 | 데이터 최대 8바이트 | 최대 64바이트•**구간 가속** | 최대 2048바이트•고속 전송 |
| 한계 | 낮은 대역폭 | 기존 CC 노드와 혼재 제약 | 장비•물리망 설계 복잡성 |

#### 한줄 요약

- 짧은 제어값은 CAN CC, 더 큰 자료는 CAN FD, 대용량 백본 연계는 CAN XL이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 기아**: 높은 우선순위 프레임이 반복되어 낮은 우선순위 프레임 전송이 계속 지연되는 현상이다.
- **최악 응답 시간**: 가장 불리한 중재•재전송 조건에서 프레임 전송을 완료하기까지 걸리는 최대 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고부하의 **우선순위 기아** | **최악 응답 시간**과 버스 부하 분석 | 긴급성과 주기 보장 |
| 배선 반사의 프레임 오류 | 토폴로지•종단•길이 검증 | 신호 무결성과 재전송 감소 |
| 고장 ECU의 오류 프레임 반복 | 오류 카운터와 **버스 오프** 복구 | 장애 노드의 영향 격리 |

#### 한줄 요약

- 급제동 프레임에 작은 ID를 주되 낮은 우선순위 메시지도 제한 시간 안에 전송되는지 함께 계산해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CAN 세대 선택**: 제어 주기•데이터 크기•대역폭•ECU 호환성으로 CC•FD•XL을 결정하는 과정이다.

</details>

- **CAN 세대 선택**에서 8바이트 주기 제어는 **CAN CC**, 중용량 고속은 **CAN FD**, 백본은 **CAN XL**이 핵심이다.

#### 한줄 요약

- 프레임의 긴급 순위를 먼저 정하고 데이터 크기와 기존 ECU 호환성에 맞춰 CAN 세대를 선택한다.
