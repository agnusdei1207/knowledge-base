## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN(Controller Area Network)**: 차량 내 다수의 전자제어장치(ECU)들이 호스트 컴퓨터 없이 꼬임선 2선(CAN_H, CAN_L)의 공유 버스 상에서 실시간 메시지를 교환할 수 있도록 Bosch가 개발하고 ISO 11898로 표준화한 직렬 통신 프로토콜.
- **전자제어장치(Electronic Control Unit, ECU)**: 엔진, 변속기, ABS 브레이크, 에어백, 조향 장치 등을 소프트웨어 알고리즘으로 정밀 제어하는 차량 내부 임베디드 컴퓨터.

</details>

- 정의/개념: 차량 내 복수의 ECU가 단일 2선식 차동 버스(Differential Bus)를 공유하며, 메시지 식별자(ID) 기반의 **비파괴 비트 단위 중재(CSMA/CD with Non-Destructive Bitwise Arbitration)** 와 **차동 전압 시그널링** 을 통해 충돌 없이 우선순위 통신을 보장하는 **차량용 표준 직렬 통신망 (ISO 11898)**
- 배경/필요성: 차량 전장화에 따라 ECU 간 1:1 점대점 배선(와이어링 하네스) 적용 시 발생하는 차량 중량 증가, 배선 복잡도 및 제조 원가 문제를 해결하고, 전자기 간섭(EMI) 환경에서 초고신뢰 통신을 달성할 요구

#### 한줄 요약
- 2선 차동 공유 버스 상에서 비파괴 비트 중재를 통해 우선순위 기반 충돌 없는 차량 통신을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우성 비트(Dominant Bit, '0')와 열성 비트(Recessive Bit, '1')**: 버스 상에 전압 차(2V 이상)가 인가되는 우성 비트와 전압 차가 0V인 열성 비트의 물리적 특성으로, 우성과 열성이 동시 인가되면 논리적 AND(와이어드 AND) 결합에 의해 우성 비트('0')가 버스를 점유.
- **비파괴 중재(Non-Destructive Arbitration)**: 복수의 노드가 동시 송신을 개시할 때 식별자(ID)를 비트 단위로 비교하여, 낮은 ID(높은 우선순위)를 가진 노드는 중단 없이 송신을 지속하고 높은 ID 노드는 즉각 수신 모드로 전환하는 방식.

</details>

- **메시지 지향 우선순위 방송(Broadcast)**: 수신 노드 주소 대신 11비트/29비트 메시지 ID를 부여하여 중요도 순으로 버스 점유권 부여
- **충돌 시 데이터 손실 제로(Zero-Loss)**: 이더넷과 달리 충돌 발생 시에도 최고 우선순위 메시지가 재전송 지연 없이 라인 레이트로 즉시 전송 완료
- **결함 감금(Fault Confinement) 및 버스 오프(Bus-Off)**: 지속적으로 에러 프레임을 유발하는 결함 ECU를 감지하여 Error Passive 및 Bus-Off 상태로 버스에서 자동 물리적 격리

#### 한줄 요약
- 비파괴 우선순위 중재, 우성/열성 차동 전압 전송, 결함 감금을 통한 자가 복원력을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **차동 전압 신호(CAN_H / CAN_L)**: 외부 노이즈(EMI)가 두 선에 동일하게 유입될 때 수신단에서 두 선의 전압 차($V_{\text{diff}} = V_{\text{CAN\_H}} - V_{\text{CAN\_L}}$)만을 증폭하여 공통 모드 잡음(Common-Mode Noise)을 상쇄하는 물리 계층 기술.
- **종단 저항(Terminating Resistor, 120$\Omega$)**: CAN 버스 양단에 선로의 특성 임피던스(120$\Omega$)와 일치하는 저항을 병렬 연결하여 고주파 신호 반사파(Echo)를 흡수·제거하는 수동 소자.

</details>

```text
[ 마이크로컨트롤러 (MCU) ] ── (SPI / 메모리 맵) ──▶ [ CAN 컨트롤러 (MAC 계층) ]
                                                              │ (TxD / RxD 로직 신호)
                                                              ▼
                                                     [ CAN 트랜시버 (PHY 계층) ]
                                                              │
   ┌──────────────────────────────────────────────────────────┴──────────────────────────────────────────────────────────┐
   ▼ (CAN_H: 2.5V ➔ 3.5V)                                                                                                 ▼ (CAN_H)
[ 120Ω 종단 저항 ] ══════════════════════════════ [ 차동 꼬임선 (Twisted Pair) ] ══════════════════════════════ [ 120Ω 종단 저항 ]
   ▲ (CAN_L: 2.5V ➔ 1.5V)                                                                                                 ▲ (CAN_L)
   └──────────────────────────────────────────────────────────┬──────────────────────────────────────────────────────────┘
                                                              │
                                                     [ 타 ECU CAN 노드 ]
```

선의 의미: MCU의 데이터가 CAN 컨트롤러와 트랜시버를 거쳐 꼬임선 버스 상의 차동 전압으로 변환 송출되고, 양단 종단 저항이 반사파를 억제하는 물리 토폴로지

| 구성요소 | 책임 및 역할 | 비고 |
|:---|:---|:---|
| **CAN 컨트롤러 (MAC)** | 프레임 조립/분해, 비트 스터핑, CRC 계산, 비파괴 중재 및 에러 카운터 관리 | ISO 11898-1 |
| **CAN 트랜시버 (PHY)** | 디지털 로직(TTL) 신호를 CAN_H/CAN_L 차동 아날로그 전압으로 상호 변환 | ISO 11898-2 |
| **차동 꼬임선 버스** | 외부 EMI 전자기 유도 노이즈를 상쇄하는 물리적 2선 통신 매체 | CAN_H, CAN_L |
| **종단 저항 (120$\Omega$)** | 전송선로 임피던스 정합을 통해 신호 반사파 왜곡을 방지 (양단 각 1개, 합성 60$\Omega$) | 특성 임피던스 매칭 |

#### 한줄 요약
- CAN 컨트롤러, 트랜시버, 차동 꼬임선, 120옴 종단 저항이 결합하여 강인한 차량 버스를 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ACK 슬롯(Acknowledgment Slot)**: 송신 노드가 프레임 끝부분에서 열성('1') 비트를 송출할 때, 메시지를 에러 없이 수신한 모든 노드가 동시에 우성('0') 비트를 덮어써서(Overwrite) 정상 수신을 증명하는 비트.

</details>

```text
1. 버스가 유휴(Idle) 상태임을 감지한 복수의 ECU가 SOF(Start of Frame: 0)를 동시에 송출
            │
            ▼
2. 각 노드가 자신의 식별자(ID) 비트를 최상위 비트(MSB)부터 1비트씩 버스에 인가하고 동시 모니터링
            │
            ▼
3. [중재 판정]: 노드가 열성('1')을 송출했으나 버스 상에서 우성('0')이 검출된 경우 즉시 송신 중단 및 수신 모드 전환
            │
            ▼
4. 최우선 순위(최소 ID)를 가진 승자 노드가 중단 없이 페이로드 데이터와 CRC 필드 연속 송출
            │
            ▼
5. 수신 노드들이 CRC 무결성을 검증하고 ACK 슬롯에 우성('0') 비트를 인가하여 송신 성공 확정
```

**동작 원리**

1. **동시 송신 개시**: 모든 노드가 클럭 동기화를 맞추며 첫 우성 비트(SOF)를 버스에 주입
2. **비트 단위 중재**: 와이어드 AND 버스 특성으로 인해 '0'을 송출한 노드가 버스 제어권 획득
3. **패자 양보**: 열성('1')을 송출한 노드는 자신이 보낸 비트와 버스 상태 불일치를 감지하고 즉시 침묵
4. **승자 데이터 전송**: 중재에서 승리한 노드는 1비트의 데이터 훼손도 없이 프레임 전송 완수
5. **분산 수신 확인**: 수신측 노드 중 단 하나라도 정상 수신하면 ACK 슬롯이 '0'으로 구동

#### 한줄 요약
- SOF 송출, 비트 단위 ID 중재, 패자 수신 전환, 승자 데이터 전송, ACK 수신 확인 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAN CC vs CAN FD vs CAN XL**: 클래식 CAN(8B/1Mbps), 가변 비트 전송률 CAN FD(64B/5Mbps), 차세대 초대용량 CAN XL(2048B/10Mbps+).

</details>

| 비교 항목 | 클래식 CAN (CAN 2.0 / CC) | CAN FD (Flexible Data-rate) | CAN XL (Extra Long) |
|:---|:---|:---|:---|
| **최대 데이터 페이로드**| **최대 8 Bytes** | **최대 64 Bytes** | **최대 2,048 Bytes (이더넷 프레임 수용)**|
| **전송 속도 (데이터 구간)**| **최대 1 Mbps 고정** | **최대 2 ~ 5 Mbps (구간 가속)** | **최대 10 ~ 20 Mbps (PWM 인코딩)** |
| **중재/데이터 구간 분리**| 단일 비트 레이트 유지 | 중재(1Mbps)와 데이터(5Mbps) 분리 | 중재(1Mbps)와 데이터(20Mbps) 분리 |
| **보안 및 이더넷 캡슐화**| 페이로드 제약으로 암호화 곤란 | SecOC(보안 온보드 통신) 적용 가능 | **이더넷 L2 패킷 터널링 및 IPsec 수용** |
| **주요 적용 영역** | 차체 제어(바디), 도어, 파워트레인 | 엔진/모터 제어, ADAS 센서 연동 | **SDV(소프트웨어 정의 차량) 존 아키텍처** |

#### 한줄 요약
- CAN 2.0은 기본 차체 제어, CAN FD는 ADAS 센서 고속화, CAN XL은 SDV 대용량 백본에 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 기아(Starvation)**: 고우선순위(낮은 ID: 브레이크, 조향) 메시지가 버스를 연속 점유할 때 저우선순위(높은 ID: 공조, 윈도우) 메시지가 무한 대기하는 현상.
- **신호 반사(Signal Reflection)**: 버스 종단에 120$\Omega$ 저항이 누락되거나 분기선(Stub Line) 길이가 과도할 때 전기 신호가 반사되어 비트 파형이 왜곡되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고우선순위 트래픽 폭주 시 저우선순위 ECU 메시지의 전송 기아 현상(Starvation) | **최악 응답 시간(WCRT) 해석 기반 주기적 메시지 ID 설계** 및 버스 부하율 70% 이하 통제 | 모든 기능의 실시간 데드라인 보장 및 스케줄링 안정성 확보 |
| 종단 저항(120$\Omega$) 미결합 또는 긴 스터브 라인으로 인한 신호 반사파 왜곡 | **양단 120$\Omega$ 분할 종단(Split Termination)** 및 스터브 길이 0.3m 이내 제한 | 신호 링잉(Ringing) 및 공통 모드 노이즈 제거, 통신 무결성 확보 |
| 결함 노드의 연속 에러 프레임 방출로 인한 버스 전체 통신 마비(Babbling Idiot) | CAN 컨트롤러의 **TEC/REC 기반 자동 버스 오프(Bus-Off) 격리** 로직 활성화 | 단일 결함 ECU의 통신망 전면 마비 차단 및 고장 격리 달성 |

#### 한줄 요약
- WCRT 분석으로 기아를 방지하고, 120옴 종단으로 반사파를 제거하며, Bus-Off로 결함 노드를 격리한다.

## Ⅶ. 결론

- 차량 내 전장 부품의 안전 제어를 위해 **비파괴 비트 중재 기반의 CAN 버스 아키텍처**가 핵심 표준으로 정착되었으며, 최근 자율주행 및 SDV(소프트웨어 정의 차량) 전환에 발맞추어 고대역폭 요구를 수용하기 위해 **CAN FD/XL** 및 **Automotive Ethernet(100BASE-T1/1000BASE-T1)** 과 통합 결합하는 존(Zonal) 네트워크 아키텍처로 진화 중

#### 한줄 요약
- 비파괴 중재와 차동 신호를 기반으로 CAN 통신은 SDV 시대의 CAN XL 및 이더넷으로 고도화되고 있다.
