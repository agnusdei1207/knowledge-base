## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **eMBB(초고속 이동통신)**: 영화 1편을 1초 만에 다운받는, 속도에 미친 5G의 대용량 스트리밍(VR/AR) 특화 서비스다.
- **URLLC(초신뢰 저지연 통신)**: 목숨이 왔다 갔다 하는 자율주행이나 원격 수술에서 딜레이(1ms)와 패킷 손실(99.999% 신뢰)을 절대 용납하지 않는 칼치기 서비스다.
- **mMTC(초고밀도 사물 통신)**: 속도는 쥐똥만 한데, 운동장 하나에 수십만 개의 센서(스마트 미터기 등)가 동시에 붙어도 안 뻗고 배터리는 10년 가는 물량전 서비스다.

</details>

- 정의: 5G가 단순한 속도 경쟁을 넘어, **초고속(eMBB), 극저지연(URLLC), 대규모 접속(mMTC)** 이라는 3가지 극단적 KPI를 동시에 만족시키는 ITU-R의 서비스 분류 체계
- 배경: 4G(LTE)처럼 하나의 획일화된 망으로는 4K 스트리밍(속도)과 자율주행(저지연), 스마트 공장(대규모 접속)의 **서로 엇갈리는 요구사항을 절대 다 품을 수 없었기 때문** #### 한줄 요약

- 속도 깡패(eMBB), 핑(딜레이) 깡패(URLLC), 물량 깡패(mMTC)로 3등분 해서 맞춤형으로 쏴주는 5G의 핵심 철학이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **네트워크 슬라이싱(Network Slicing)**: 물리적인 5G 망 하나를 가상으로 쪼개서, 유튜브용(eMBB) 뻥 뚫린 고속도로와 구급차용(URLLC) 버스전용차로를 아예 분리해 버리는 5G 핵심 기술이다.
- **서비스 품질(QoS)**: 누구한테 속도를 몰아주고, 누구한테 반응 속도를 최우선으로 빼줄지 정하는 통신망의 합법적 차별 정책이다.

</details>

- **eMBB (초고속/대용량)**: 28GHz 밀리미터파(mmWave)와 Massive MIMO 안테나를 집중 적용하여 최고 20Gbps 속도를 무식하게 뽑아냄.
- **URLLC (초저지연/초신뢰)**: 데이터를 모아서 안 보내고 즉각(Mini-slot) 쏴버리며, 코어망 안 거치고 기지국 옆(MEC)에서 바로 짬 처리해 1ms 핑을 사수함.
- **mMTC (대규모 단말 접속)**: 데이터 송수신 끝나면 단말을 깊은 수면(PSM) 상태로 기절시켜서 배터리를 10년 넘게 우려먹음.

#### 한줄 요약

- 3가지 미친 스펙을 한 번에 돌리면 망이 뻗으니까, 네트워크 슬라이싱으로 가상 차선을 찢어서 트래픽을 분리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **UPF(User Plane Function)**: 사용자의 쌩 데이터(영상, 텍스트)를 목적지로 빡세게 쏴주는 5G 코어의 우체국(라우터)이다.
- **MEC(Mobile Edge Computing)**: 딜레이 줄이려고 서울(중앙 코어망)까지 안 가고, 동네 기지국 옆에 서버(UPF)를 갖다 놓은 로컬 엣지 클라우드다.

</details>

```text
[ 5G 3대 서비스 직관적 비교 구조 ]

[ 5G 단말 (스마트폰, 자율주행차, 센서) ]
               │
(eMBB: 고속) (URLLC: 저지연) (mMTC: 저전력)
               │
               ▼
[ 5G 기지국 (gNB) / 무선 자원 제어 (RRM) ]
               │
      ┌────────┴────────┐
      │ (슬라이싱 분리) │
      ▼                 ▼
[ MEC (기지국 옆) ]  [ 중앙 5G 코어망 (UPF) ]
(URLLC 즉시 컷)      (eMBB, mMTC 처리)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **무선 자원 제어(RRM)**| 폰은 주파수 넓게, 차는 즉시 전송하게 **무선 스펙을 차별해서 쏴줌** | gNB |
| **MEC / 전진 배치 UPF**| 서울까지 가면 핑 튀니까 **기지국 옆에서 URLLC 트래픽 바로 짬 처리함** | Edge Cloud |
| **중앙 UPF** | 유튜브(eMBB)나 센서(mMTC) 데이터 모아서 **인터넷망으로 던지는 우체국** | Core |
| **네트워크 슬라이스** | eMBB, URLLC, mMTC 섞여서 뻗지 않게 **차로를 가상으로 찢어버림** | 망 분리 |

#### 한줄 요약

- 기지국이 요구사항 체크해서 차로 쪼개고(슬라이싱), 급한 놈(URLLC)은 동네(MEC)에서 끝내고 안 급한 놈은 서울(Core)로 보낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **5QI(5G QoS Identifier)**: "얘는 핑 튀면 뒤지는 자율주행 차임(우선순위 최상위)" 하고 패킷에 붙여놓는 5G 전용 VIP 식별 태그다.

</details>

```text
[ 5G 서비스 프로비저닝 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [요구사항 체크]      │
│ (너 속도 필요함? 핑 필요함?) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [5QI 식별 태그 붙이기]         │
│ (URLLC VIP 식별 태그 발부)        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [가상 차선(슬라이싱) 배정]│
│ (URLLC 전용 차선으로 몰빵)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [UPF / MEC 라우팅]        │
│ (기지국 옆 MEC에서 1ms 컷)   │
└──────────────────────────────┘
```

### 동작 원리

1. 요구사항 분석: 단말이 접속하면 이놈이 eMBB인지 URLLC인지 mMTC인지 분류함.
2. 정책(QoS) 결정: 데이터 패킷에 5QI 식별 태그를 붙여서 우선순위를 정함.
3. 자원/차선 할당: eMBB는 넓은 주파수 대역을 주고, URLLC는 대기열 맨 앞으로 새치기시킴.
4. 라우팅 경로 분리: URLLC는 기지국 옆 MEC로 빼고, 나머지는 코어망으로 쏨.

#### 한줄 요약

- 식별 태그(5QI) 붙여서 VIP인지 확인하고, 차선 분리(슬라이싱)해서 목적지(MEC vs Core)로 쏴주는 과정이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Mini-slot**: 보통 데이터를 묶음(14 심볼)으로 모았다가 보내는데, URLLC는 다 무시하고 2개 심볼만 모여도 냅다 쏴버리는 새치기 전송 기술이다.
- **PSM(Power Saving Mode)**: 센서가 하루에 한 번만 데이터 쏘고 나머지 시간은 완전 기절(수면) 모드로 들어가 배터리 10년 쓰게 만드는 mMTC 기술이다.

</details>

| 구분 | **eMBB (속도 깡패)** | **URLLC (딜레이 깡패)** | **mMTC (물량 깡패)** |
|:---|:---|:---|:---|
| 직관적 비교 목표 | 4K/8K, VR/AR **초고속 스트리밍** | 자율주행, 원격수술 **1ms 핑 사수** | 스마트 미터기 **100만 개 동시 접속** |
| 핵심 무선 기술 | 주파수 매우 넓게 씀 (밀리미터파) | 모으기 전에 냅다 쏨 (Mini-slot) | 한 번 쏘고 기절시킴 (PSM, eDRX) |
| 코어 처리 기술 | 고용량 처리하는 **중앙 UPF 빵빵하게** | 기지국 옆에 **MEC/UPF 전진 배치** | 가벼운 트래픽만 모아서 처리 |
| 치명적 병목점 | 기지국과 코어망 사이 **유선 랜선 폭발** | 처리 늦어져 **1ms 핑 튀면 사람 죽음**| 100만 개 동시 접속에 코어망 마비 |

#### 한줄 요약

- 5G는 eMBB로 눈을 즐겁게 하고, URLLC로 목숨을 살리며, mMTC로 온 세상의 사물들을 연결한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **E2E Latency Budget(종단 지연 예산)**: "단말 $\to$ 기지국 $\to$ 코어망 $\to$ 단말" 이 전체 구간을 합쳐서 무조건 1ms(URLLC) 안에 끝내야 하는 빡센 마지노선 타임어택이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 유튜브 보는 놈들 땜에 **자율주행 핑이 튀어서 사고 남** | eMBB 뚱뚱한 트래픽이 URLLC 자원 대역을 침범 (자원 간섭) | **네트워크 슬라이싱** 켜서 자원 논리/물리 엄격한 통제없이 찢음 | VIP 트래픽(URLLC) 간섭 방어 및 생명 보장 |
| URLLC 설정 다 했는데 **자꾸 핑이 10ms 넘게 튀어버림** | 서울(중앙망)까지 트래픽이 찍고 오느라 발생하는 왕복 딜레이 | 기지국 근처에 **MEC 및 UPF 전진 배치(Edge Offloading)** | E2E 지연 1ms 이내 타임어택 성공 |
| 새해 종 칠 때 센서 100만 개 접속해서 **코어망 뻗어버림** | 수많은 mMTC 단말이 접속 요청(제어 메시지) 무지성 폭격 | 코어망에서 접속 시도 억제(Throttle) 및 수면(PSM) 시간 분산 | 코어망 C-Plane 뻗는 대규모 네트워크 장애 방어 |
| 가상 차로(슬라이스) 나눠놨는데 **트래픽 몰릴 때 효율 비효율적 상태** | 낮엔 공장(URLLC), 밤엔 집(eMBB) 트래픽이 고정 할당돼서 낭비 | AI 기반 동적 자원 스케줄링(Dynamic Slicing) 적용 | 망 운용 효율성 및 자원 활용률 극대화 |

#### 한줄 요약

- 자원 섞이면 죽음이니까 슬라이싱으로 완벽히 찢고, URLLC 트래픽은 무조건 기지국 옆 MEC에서 컷해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 초고속 데이터는 **eMBB**, 생명 직결 실시간 제어는 **URLLC**, 대규모 센서는 **mMTC** 기반 트래픽을 완벽히 분리하고, **MEC(전진 배치)** 와 **네트워크 슬라이싱** 통해 서비스별 KPI 훼손을 원천 차단하는 5G 아키텍처 기조 확립함

#### 한줄 요약

- 5G의 위대함은 단순히 속도가 빨라진 게 아니라, 서로 다른 요구사항을 가진 트래픽들을 하나의 망에서 완벽하게 분리 통제하는 데 있다.
