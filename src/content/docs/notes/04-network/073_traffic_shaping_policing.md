## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **트래픽 셰이핑(Traffic Shaping)**: 초과 패킷을 큐에 저장해 지연 전송하는 제어 기법이다.
- **트래픽 폴리싱(Traffic Policing)**: 초과 패킷을 폐기하거나 재표시하는 제어 기법이다.

</details>

- 정의/개념: **트래픽 셰이핑**과 **트래픽 폴리싱**은 토큰 판정으로 속도와 버스트를 제한하는 제어 기법이다.
- 배경/필요성: 제한 없는 버스트는 계약을 위반하거나 하위 회선을 혼잡하게 한다.

#### 한줄 요약

- 약속한 속도를 넘은 패킷을 기다렸다 보내거나 버려 회선에 한꺼번에 몰리지 않게 한다.

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **버스트 허용**: 버킷에 미리 축적한 토큰 범위에서 장기 평균 속도보다 큰 순간 전송을 허용하는 성질이다.

</details>

- 토큰 생성률로 장기 평균 전송률을 제한한다.
- **버스트 허용** 범위는 버킷 크기로 결정한다.
- 초과 패킷은 대기•폐기•재표시 정책으로 처리한다.

#### 한줄 요약

- 버킷이 크면 더 큰 버스트를 허용하므로 하위 회선 수용량과 함께 조정한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **토큰 버킷**: 일정 속도로 생성되는 토큰과 패킷 크기를 비교해 약정 적합•초과 트래픽을 판정하는 방식이다.
- **약정 정보율(Committed Information Rate, CIR)**: 장기적으로 보장하거나 허용하는 평균 정보율이다.
- **최대 정보율(Peak Information Rate, PIR)**: 순간적으로 허용하는 최대 정보율이다.

</details>

- **토큰 버킷**은 **CIR**과 **PIR**•버킷 크기로 패킷의 약정 적합 여부를 판정한다.

```text
분류기
└─ 토큰 버킷
   ├─ 셰이퍼
   └─ 폴리서
```

선의 의미: 분류기 아래의 토큰 버킷이 공통 속도•버스트 판정 계층을 이루고, 셰이퍼와 폴리서가 서로 다른 초과 트래픽 집행 경계를 구성하는 정적 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 분류기 | 서비스 등급•정책 대상 구분 |
| 토큰 버킷 | CIR•PIR•버스트로 적합•초과 판정 |
| 셰이퍼 | 초과분 큐 저장•지연 전송 |
| 폴리서 | 초과분 폐기•등급 변경 |

#### 한줄 요약

- 토큰 버킷이 초과를 판정하면 셰이퍼나 폴리서가 처리한다.

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **차등 서비스 코드 포인트(Differentiated Services Code Point, DSCP)**: 패킷의 서비스 등급을 표시하는 IP 헤더 값이다.
- **정책•패킷 크기 전달**: 가입자 속도 정책과 패킷 전송에 필요한 토큰 수를 판정기에 제공하는 단계이다.
- **토큰 적합 판정**: 잔여 토큰과 패킷 크기를 비교해 약정 적합•초과를 결정하는 단계이다.
- **초과 패킷 큐 저장**: 셰이핑 대상 초과 패킷을 토큰이 보충될 때까지 버퍼에 보관하는 단계이다.
- **초과 패킷 집행**: 폴리싱 대상 초과 패킷을 폐기하거나 낮은 서비스 등급으로 재표시하는 단계이다.

</details>

```text
패킷 입력•정책 분류
      │
      ▼
1. 정책•패킷 크기 전달
      │
      ▼
2. 토큰 적합 판정
      ├─ 적합: 즉시 전송
      └─ 초과
          ├─ 셰이핑 정책
          │      └─ 3. 초과 패킷 큐 저장
          │              └─ 토큰 생성 후 지연 전송
          └─ 폴리싱 정책
                 └─ 4. 초과 패킷 집행
                         └─ 폐기 또는 DSCP 재표시
```

### 동작 원리

1. **정책•패킷 크기 전달**: **정책•패킷 크기 전달** 단계에서 가입자 정책과 필요 토큰을 계산한다.
2. **토큰 적합 판정**: **토큰 적합 판정** 단계에서 잔여 토큰과 패킷 크기를 비교한다.
3. **초과 패킷 큐 저장**: **초과 패킷 큐 저장** 단계에서 토큰 생성까지 버퍼에서 대기한다.
4. **초과 패킷 집행**: **초과 패킷 집행** 단계에서 즉시 폐기하거나 **DSCP**를 재표시한다.

#### 한줄 요약

- 패킷 크기만큼 토큰이 있으면 즉시 보내고 부족하면 정책에 따라 기다리거나 폐기한다.

## Ⅴ. 종류 및 비교

| 트래픽 속도 제어 | 트래픽 셰이핑 | 트래픽 폴리싱 |
|:---|:---|:---|
| 적용 기준 | **트래픽 셰이핑**은 출구 전송률 평탄화 | **트래픽 폴리싱**은 입구 계약 한도 집행 |
| 핵심 특징 | 초과 패킷 큐 대기 | 초과 패킷 폐기•재표시 |
| 한계 | 큐 지연•버퍼 오버플로 | 손실•상위 프로토콜 재전송 |

> 요약: 대기는 셰이핑, 즉시 집행은 폴리싱이다.

#### 한줄 요약

- 셰이퍼 버스트가 폴리서보다 크면 경계에서 폐기된다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **응답 지연 초과**: 셰이핑 큐가 계속 늘어 패킷이 응용의 지연 한도보다 오래 대기하는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 셰이퍼 버스트가 경계 폴리서 초과 | 양단 **CIR**•버킷 크기 정렬 | 경계 폐기 감소 |
| 셰이핑 큐 증가로 **응답 지연 초과** | 지연 한도•버퍼 상한 설정 | 응답 시간 보호 |
| 폴리싱 폐기로 상위 재전송 증가 | 재표시•응용 영향 함께 분석 | 불필요 재전송 감소 |

#### 한줄 요약

- 지사 라우터가 초과 패킷을 버퍼에서 지연시켜 계약 속도로 전송함으로써 사업자 폴리서의 폐기를 줄인다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **초과 트래픽 처리 선택**: 지연 허용 여부와 계약 한도 집행 위치를 기준으로 트래픽 셰이핑과 트래픽 폴리싱을 결정하는 기준이다.

</details>

- **초과 트래픽 처리 선택**에서 대기가 가능하면 **트래픽 셰이핑**, 계약 한도 즉시 집행은 **트래픽 폴리싱**이 핵심이다.

#### 한줄 요약

- 기다려도 되는 초과분은 셰이핑, 계약 한도를 즉시 집행해야 하면 폴리싱을 사용한다.
