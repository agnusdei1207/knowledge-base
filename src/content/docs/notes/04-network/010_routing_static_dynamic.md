## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Static Routing (정적 라우팅)**: 네트워크 관리자가 목적지 네트워크로 가는 넥스트홉(Next-Hop) 경로를 라우터에 수동으로 직접 고정 설정하는 방식.
- **Dynamic Routing (동적 라우팅)**: OSPF, BGP 등 라우팅 프로토콜이 라우터 간 토폴로지 정보를 상호 교환하여 최적 경로를 자동 계산하고 갱신하는 방식.

</details>

- 정의/개념: L3 패킷의 최적 경로를 결정하기 위해 **관리자가 수동 고정하는 정적 라우팅과 프로토콜을 통해 토폴로지를 자동 학습하는 동적 라우팅**
- 배경/필요성: 복잡한 엔터프라이즈 및 인터넷 백본 네트워크에서 수동 정적 라우팅 설정에만 의존할 경우 네트워크 규모 확장에 따른 관리 비용 폭증, 링크 장애 발생 시 수동 경로 절체로 인한 장시간 통신 두절 및 트래픽 블랙홀 현상을 방지하고, 반대로 동적 라우팅 프로토콜만 사용할 때의 라우터 CPU/메모리 오버헤드와 비대칭 라우팅 위험을 통제하기 위해, 관리 거리(AD)와 메트릭 기반의 신뢰도 우선순위 및 제어 평면(RIB)과 고속 데이터 평면(FIB)을 분리한 정적·동적 복합 라우팅 체계를 도입하여 **규모에 따른 유연한 경로 수렴(Convergence)과 서브세컨드 무중단 장애 복원력**을 달성할 필요

#### 한줄 요약
- 관리 거리(AD)와 메트릭으로 최적 경로를 선별하고, RIB/FIB 분리를 통해 하드웨어 고속 포워딩을 구현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Administrative Distance (AD, 관리 거리)**: 서로 다른 라우팅 프로토콜 출처 간의 신뢰도를 나타내는 가중치 (Direct: 0, Static: 1, OSPF: 110, RIP: 120, External BGP: 20).
- **Metric (메트릭)**: 동일 라우팅 프로토콜 내에서 최적 경로를 결정하는 비용 기준 (OSPF: 대역폭 기반 Cost, RIP: 홉 수 Hop Count, BGP: AS-Path/MED).

</details>

- 프로토콜 출처 간 신뢰도를 비교하여 최적 경로를 선정하는 **관리 거리(Administrative Distance)**
- 동일 프로토콜 내에서 링크 비용을 수치화하여 최단 경로를 계산하는 **메트릭(Metric) 기준선**
- 제어 평면(RIB)의 최적 경로만을 데이터 평면(FIB) 하드웨어에 적재하는 **제어/데이터 평면 분리**

#### 한줄 요약
- AD 신뢰도, 메트릭 비용 계산, RIB/FIB 평면 분리를 통해 최적의 L3 스위칭을 수행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RIB (Routing Information Base)**: 모든 라우팅 프로세스로부터 수집된 후보 경로를 저장하고 최적 경로를 연산하는 제어 평면(Control Plane) 소프트웨어 DB.
- **FIB (Forwarding Information Base)**: RIB에서 선발된 최적 경로와 넥스트홉 MAC을 TCAM 메모리에 적재하여 라인 레이트 포워딩을 수행하는 데이터 평면(Data Plane) 테이블.

</details>

```text
[L3 라우터]
|-- 제어 평면
|   |-- 정적 경로
|   |-- 동적 라우팅 프로토콜
|   `-- RIB
`-- 데이터 평면
    |-- FIB
    `-- 인접성 테이블
```

선의 의미: 계층 및 제어 평면의 다양한 출처 경로가 RIB에서 평가되어 최적 엔트리만 하드웨어 FIB로 복제되어 고속 포워딩되는 구조

| 구성요소 | 책임 |
|:---|:---|
| **관리 거리** | 서로 다른 경로 출처의 우선순위 비교 |
| **메트릭** | 동일 프로토콜의 후보 경로 비교 |
| **RIB** | 후보 경로 저장과 최적 경로 선발 |
| **FIB** | 목적지 프리픽스 기반 패킷 전달 |
| **ECMP** | 등가 경로 사이 트래픽 분산 |

#### 한줄 요약
- FIB는 소프트웨어 RIB 탐색을 패킷마다 반복하는 비용을 피하려고 선발된 최적 경로만 TCAM에 복제한 사본 계층이며, 관리 거리와 메트릭은 무엇을 복제할지 고르는 기준으로만 제어 평면에 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **L3 포워딩 4단계**: 경로 수집 및 RIB 적재 $\to$ AD/메트릭 최적 경로 선발 $\to$ FIB/인접성 테이블 프로그래밍 $\to$ TCAM LPM 고속 포워딩.

</details>

```text
1. 경로 정보 수집
      |
2. 최적 경로 선발
      |
3. FIB 프로그래밍
      |
   [링크 장애?]
    /       \
 아니오      예
  |           |
4. LPM 전달  재수렴 후 2번
  |
[패킷 송출]
```

- 1. 경로 정보 수집: 정적·동적 후보를 RIB에 저장
- 2. 최적 경로 선발: 출처 우선순위와 메트릭 비교
- 3. FIB 프로그래밍: 최적 프리픽스와 넥스트홉 반영
- 4. LPM 전달: 목적지와 가장 긴 **프리픽스** 선택

#### 한줄 요약
- 정상 경로는 FIB의 LPM 룩업 한 번으로 끝나지만 링크 장애로 갈라지면 경로 재선발과 FIB 재적재를 다시 치러야 하므로, 제어 평면의 재수렴 시간이 곧 포워딩 공백 시간이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Convergence Time (수렴 시간)**: 네트워크 장애 발생 시 모든 라우터가 토폴로지 변경을 공유하고 새로운 일관된 라우팅 테이블을 완성하기까지 걸리는 시간.

</details>

| 비교 항목 | 정적 라우팅 (Static Routing) | 동적 라우팅 (Dynamic Routing) |
|:---|:---|:---|
| 경로 관리 | 관리자 수동 설정 | 프로토콜 자동 학습 |
| 장애 대응 | 추적·백업 설정 없이는 수동 우회 | **자동 수렴** 가능 |
| 제어 부하 | 라우팅 교환 부하 없음 | 제어 메시지와 경로 계산 부하 |
| 적용 규모 | 소규모·말단 네트워크 | 대규모·다중 경로 네트워크 |
| 보안 통제 | 설정 권한과 변경 감사 | 인접 인증과 경로 정책 |

#### 한줄 요약
- 정적 라우팅은 자원 소모가 적고 단순하며, 동적 라우팅은 장애 발생 시 자동 복원력을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Floating Static Route (부동 정적 경로)**: 평상시에는 동적 라우팅(OSPF AD=110)을 사용하다가 동적 경로가 끊기면 높은 AD(예: AD=200)로 설정된 정적 백업 경로가 활성화되는 기법.
- **IP SLA Tracking**: 정적 경로의 넥스트홉으로 주기적 ICMP 핑을 발송하여 회선 장애 감지 시 정적 경로를 라우팅 테이블에서 즉시 제거하는 헬스체크 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정적 라우팅 환경에서 원격 링크 단선 시 트래픽 블랙홀 발생 | **정적 경로에 `IP SLA ICMP 프로브 및 Track` 객체 연동** | 회선 장애 시 정적 경로 자동 회수 및 우회 |
| 이종 프로토콜 간 경로 재분배 시 상호 재유입으로 라우팅 루프 | **재분배 시 `Route-Map 태그(Route Tag) 및 Prefix-List` 필터링** | 재분배 경로의 역유입 차단 및 루프 방지 |
| 다중 경로 환경에서 비대칭 라우팅(Asymmetric Routing)으로 방화벽 차단 | **메트릭 조정을 통해 송수신 `대칭 경로(Symmetric Path)` 강제** | Stateful 방화벽 세션 정합성 보장 |
| 코어 동적 라우터 장애 시 백업 경로 절체 지연 | **AD 값을 높게 설정한 `Floating Static Route` 및 BFD 초고속 감지** | 서브세컨드(Sub-second) 고속 페일오버 |

#### 한줄 요약
- IP SLA 트래킹, 재분배 태그 필터링, 대칭 경로 강제, Floating Static으로 운영한다.

## Ⅶ. 결론

- 단순한 스텁(Stub) 네트워크부터 대규모 다중 경로 데이터센터 및 하이브리드 클라우드 백본에 이르기까지 **최적의 L3 패킷 포워딩과 네트워크 고가용성을 지탱하는 가장 본질적인 트래픽 제어 아키텍처**로 확립되었으며, 실무 구축 시에는 **내부 코어망 OSPF 동적 수렴, 외부 ISP 연동 BGP 정책 제어, 회선 장애 시 자동 우회를 위한 IP SLA 연동 Floating Static Route 구성, 이종 프로토콜 재분배 시 루프를 방지하는 Route-Map 태깅 및 BFD(Bidirectional Forwarding Detection) 연계**를 결합하여 견고한 L3 네트워크를 완성

#### 한줄 요약
- 정적 라우팅의 명시적 제어성과 동적 라우팅의 자동 수렴성을 유기적으로 결합하여 고신뢰 L3 인프라를 구축한다.
