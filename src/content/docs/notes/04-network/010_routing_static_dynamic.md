## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **라우팅(Routing)**: 택배 상자(패킷)에 적힌 도착지 주소(IP)를 보고, 지도(라우팅 테이블)를 펴서 가장 빠르고 막히지 않는 골목(최적 경로)을 찾아 짐을 넘겨주는 네비게이션 역할이다.
- **인터넷 프로토콜(IP, Internet Protocol)**: 전 세계 컴퓨터가 서로를 찾기 위해 패킷에 붙이는 32비트짜리 송장 번호(논리적 주소)이다.

</details>

- 정의: 목적지 IP 주소를 참조하여 지도상에서 가장 빠르고 막히지 않는 최적 경로를 찾아주는 **L3 네비게이션 과정**
- 배경: 단일 랜선으로는 앞집밖에 못 가므로, 전 세계 거미줄처럼 얽힌 망을 넘으려면 **똑똑한 길 찾기가 필요했기 때문**

#### 한줄 요약

- 수많은 갈림길 중에서 가장 비용이 싸고 빠른 출구(Next Hop)를 찾아 패킷을 던져주는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **관리 거리(AD, Administrative Distance)**: 여러 명의 길잡이가 서로 자기가 맞다고 우길 때, "난 관리자가 직접 찍어준 정적 라우팅을 최우선으로 믿겠다" 하고 정해놓은 신뢰도 점수(낮을수록 짱)이다.
- **메트릭(Metric)**: 같은 길잡이가 여러 갈래 길을 찾아왔을 때, "거긴 대역폭이 좁고(Cost 큼), 여긴 홉(Hop) 수가 적어서 빠르네" 하고 계산한 진짜 통행료(비용)이다.
- **제어 평면(Control Plane)과 데이터 평면(Data Plane)**: 머리로 지도를 그리고 계산하는 게 제어 평면(CPU)이고, 그 지도를 보고 들어온 짐을 무지성으로 빠르게 쏴버리는 게 데이터 평면(ASIC 칩)이다.

</details>

- 여러 라우팅 출처가 싸울 땐 **관리 거리(AD)** 를 기준으로 신뢰도가 가장 높은 놈의 말을 들음 (Direct > Static > OSPF).
- 같은 프로토콜이 가져온 길 중에선 **메트릭(비용)** 이 가장 싼 길을 최적 경로로 산출.
- 머리 쓰는 **제어 평면**과 몸 쓰는 **데이터 평면**으로 완벽하게 역할을 찢어놔서 스위칭 속도 극대화.

#### 한줄 요약

- AD 점수와 메트릭 비용으로 1등 경로를 뽑고, 머리와 몸을 분리해서 처리 속도를 끌어올린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **라우팅 정보 베이스(RIB, Routing Information Base)**: 길잡이들이 가져온 모든 경로의 경우의 수를 다 쑤셔 넣어둔 지저분한 초안 지도(제어 평면 메모리)이다.
- **포워딩 정보 베이스(FIB, Forwarding Information Base)**: 초안(RIB)에서 AD랑 메트릭으로 다 쳐내고, 진짜배기 1등 경로만 추려서 고속 칩(TCAM)에 구워 넣은 실전용 족보이다.
- **최장 프리픽스 일치(LPM, Longest Prefix Match)**: 족보를 뒤질 때, "10.0.0.0/8"보다 "10.1.1.0/24"처럼 목적지 IP와 더 길고 구체적으로 똑같은 길을 우선 찾는 검색 룰이다.

</details>

```text
[ 직관적 비교 기반 라우팅 계층 아키텍처 ]

[ 여러 길잡이들 (Static, OSPF, BGP) ]
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ [ 제어 평면 (머리 쓰는 곳) ]                            │
│ 1. RIB (초안 장부): 오만가지 길 다 긁어모음             │
│ 2. AD & 메트릭 배틀: 1등 경로만 뽑아냄                  │
└────────────────────────────────────────────────────────┘
                   │ 1등 경로만 하사함
                   ▼
┌────────────────────────────────────────────────────────┐
│ [ 데이터 평면 (몸 쓰는 곳) ]                            │
│ 3. FIB (고속 족보): 하드웨어 칩(TCAM)에 구워버림       │
│ 4. 패킷 꽂히면 LPM 룰로 기계적으로 쏴버림               │
└────────────────────────────────────────────────────────┘
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **관리 거리 (AD)** | "OSPF보다 관리자가 손으로 친(Static) 말이 더 찐이다!" 하고 서열을 정하는 신뢰도 | 낮을수록 대빵임 |
| **메트릭 (Metric)**| 같은 놈이 알려준 길 중에서 톨게이트 비용(대역폭, 지연 등)이 제일 싼 길 찾기 | 프로토콜마다 다름 |
| **RIB (초안 장부)**| 온갖 동네에서 들은 길 정보를 다 적어놓고 최적 경로를 뽑아내는 소프트웨어 DB | CPU랑 RAM 까먹음 |
| **FIB (실전 족보)**| RIB에서 1등만 뽑아서 반도체에 박아넣은 **LPM 전용 고속 컨닝 페이퍼** | 하드웨어(TCAM) 씀 |
| **ECMP (다중 경로)**| 1등 경로가 2개 이상이면 버리지 않고 트래픽을 노나 보내는 로드 밸런싱 | 링크 대역폭 뽕뽑기 |

#### 한줄 요약

- 수많은 길 중에서 AD와 메트릭으로 1등만 뽑아 FIB라는 반도체 족보에 굽고 기계적으로 패킷을 쏜다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **최선 경로 선택(Best Route Selection)**: RIB에 모인 수많은 길 중에 1빠로 AD 점수, 2빠로 메트릭 점수를 따져서 단 하나의 우승자를 뽑는 오디션이다.
- **FIB 경로 설치(FIB Installation)**: 우승한 경로를 하드웨어 반도체(FIB)에 집중 적용하여서, CPU 개입 없이 미친 속도로 패킷을 넘길 수 있게 세팅하는 과정이다.

</details>

```text
[ 라우팅 테이블 생성 및 패킷 포워딩 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. [RIB 수집] 경로 긁어모음  │
│ (길잡이들이 지도 들고 옴)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [최선 경로 오디션] 1등 선발│
│ (AD가 낮고 Metric 싼 놈 승리)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [FIB 설치] 족보 굽기      │
│ (1등 경로를 고속 칩에 집중 배치)│
└──────────────┬───────────────┘
               ▼ (패킷이 들어왔다!)
┌──────────────────────────────┐
│ 4. [LPM 조회] 기계적 포워딩  │
│ (목적지와 가장 긴 비트 매칭) │
└──────────────────────────────┘
```

### 동작 원리

1. 후보 경로 수집: 정적 라우팅이나 동적 라우팅에서 수많은 경로를 RIB로 가져옴.
2. 최선 경로 선택: 가장 신뢰하는 놈(AD 우선)의 가장 싼 길(메트릭)을 우승자로 발탁함.
3. FIB 경로 설치: CPU가 놀 수 있게, 뽑힌 경로를 하드웨어 테이블(FIB)에 심어버림.
4. LPM 경로 조회: 패킷이 들어오면 FIB를 뒤져서 가장 디테일하게 일치하는(LPM) 출구로 던져버림.

#### 한줄 요약

- 장부에 다 적고(RIB) $\to$ 1등 뽑아서 칩에 굽고(FIB) $\to$ 기계적으로 가장 똑같은 길(LPM)로 던진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 라우팅(Static Routing)**: 네트워크 아저씨가 키보드로 "이 IP는 무조건 저기로 가라" 하고 라우터에 평생 고정 명시해버리는 막노동 방식이다.
- **동적 라우팅(Dynamic Routing)**: 라우터끼리 OSPF 같은 프로토콜로 "나 여깄다, 내 뒤엔 얘들 있다" 하고 지들끼리 쑥덕거려서 지도를 자동으로 그리는 방식이다.
- **수렴(Convergence)**: 랜선이 끊어졌을 때, 동적 라우팅이 "길 끊겼대! 저쪽으로 우회하자!" 하고 모든 라우터가 새 지도를 동기화 완료한 평온한 상태이다.

</details>

| 비교 항목 | **정적 라우팅 (수동 노가다)** | **동적 라우팅 (오토매틱)** |
|:---|:---|:---|
| 경로 설정 방식 | 관리자가 라우터마다 한 땀 한 땀 CLI 명령어 치고 앉아있음 | 지들끼리 프로토콜 패킷 주고받아서 알아서 지도 그림 |
| 단선 시 대응 | 관리자가 명령어로 고쳐주기 전까지 **통신 끊긴 채로 멍때림** | 끊기면 바로 옆길 찾아서 자동으로 **수렴(Convergence)** |
| 장비 리소스 낭비 | 남이랑 수다를 안 떠니까 CPU나 메모리 쓸 일이 거의 없음 | 계속 인사하고 연산하느라 CPU/RAM 뒤지게 퍼먹음 |
| 주 활용 대상 | 라우터 몇 개 없는 쪼만한 망이나 아예 말단(Stub) | 스위치 수십 개 물려있는 복잡한 본사/코어 망 |

#### 한줄 요약

- 속 편하지만 멍청한 게 정적 라우팅이고, 무겁지만 알아서 척척 장애를 우회하는 게 동적 라우팅이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **경로 추적(Route Tracking)**: 멍청한 정적 라우팅한테 "핑 때려보고 응답 없으면 이 길 당장 지워라" 하고 눈치를 달아줘서 우회로를 타게 만드는 똑똑한 기술이다.
- **경로 재분배(Route Redistribution)**: OSPF 쓰는 구역과 BGP 쓰는 구역이 말이 안 통하니까, 중간 라우터가 통역기 달고 양쪽 지도를 섞어주는(주입하는) 설정이다.
- **비대칭 라우팅(Asymmetric Routing)**: 갈 때는 A길로, 올 때는 B길로 와서, 앞뒤 맥락만 따지는 똑똑한 방화벽(Stateful)이 "어? 넌 누군데 갑자기 들어와" 하고 짝짝이 패킷을 버려버리는 억울한 장애이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 랜선이 끊겼는데 멍청한 정적 라우팅이 자꾸 끊긴 길로 쏴서 **블랙홀 생김** | 핑 때려보는 IP SLA 기반 **경로 추적(Tracking)** 달아줌 | 장애 나면 정적 경로 바로 지워버리고 정상 우회함 |
| OSPF랑 BGP 지도를 서로 통역(재분배)하다가, 지가 준 걸 다시 받아먹고 **무한 루프 돔** | 꼬리표(Tag) 달아서 자기가 줬던 경로 거르는 **재분배 필터** 적용 | 재분배 루프 터져서 라우터 뻗는 사태 원천 예방 |
| 갈 때랑 올 때 길이 달라서(비대칭), **방화벽이 짝짝이 패킷을 냅다 드롭함** | 메트릭을 강제로 조작해서 갈 때 올 때 **대칭 경로(Symmetric)** 확보 | 깐깐한 Stateful 방화벽의 세션 추적 기능 안 끊기고 유지됨 |

#### 한줄 요약

- 정적 라우팅은 핑(Tracking)으로 감시하고, 이종 간 통역은 루프 안 돌게 필터 씌우고, 길은 대칭으로 맞춰라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **라우팅 방식 결정(Routing Strategy Selection)**: 본사 한가운데는 알아서 길을 찾는 동적 라우팅(OSPF/BGP)을 깔고, 인터넷 출구나 말단 지사에는 속 편하게 정적 기본 라우팅을 박아버리는 설계 원칙이다.

</details>

- **라우팅 방식 결정** 원칙에 따라, 말단(Stub)은 속 편한 **정적 기본 경로**로 퉁치고, 복잡한 코어 망은 장애 시 수렴이 빠른 **동적 라우팅**을 적용하는 기조 확립함

#### 한줄 요약

- 단순한 말단은 손으로 찍어주는 정적 라우팅, 복잡한 코어는 알아서 도는 동적 라우팅이 정답이다.
