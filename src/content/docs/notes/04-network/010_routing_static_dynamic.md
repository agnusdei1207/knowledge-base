## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **라우팅(Routing)**: 네트워크 계층(L3)에서 수신된 IP 패킷의 목적지 주소를 기반으로 최적의 넥스트홉(Next-Hop) 경로를 결정하고 전달하는 네트워크 제어 과정.
- **포워딩(Forwarding)**: 라우터의 수신 인터페이스로 인입된 패킷을 하드웨어 스위칭 패브릭을 통해 목적지 방향의 송신 인터페이스로 신속히 이동시키는 데이터 평면 동작.

</details>

- 정의/개념: 수신 패킷의 목적지 IP 네트워크로 가기 위한 최적의 전송 경로를 수동으로 고정 구성하는 **정적 라우팅(Static)** 과 라우팅 프로토콜을 통해 토폴로지 변경을 실시간 학습하는 **동적 라우팅(Dynamic)**
- 배경/필요성: 단일 서브넷 범위를 벗어나는 분산 네트워크 환경에서 링크 장애에 대응하는 가용성을 확보하고, 네트워크 규모 확장에 따른 경로 관리 복잡도를 통제할 요구

#### 한줄 요약
- 관리자 수동 고정(정적) 또는 프로토콜 기반 자동 학습(동적)으로 최적의 L3 전송 경로를 결정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **관리 거리(Administrative Distance, AD)**: 서로 다른 라우팅 정보 출처(Direct, Static, OSPF, BGP 등) 간의 신뢰도 우선순위를 나타내는 0~255 범위의 정수값 (낮을수록 높은 우선순위).
- **메트릭(Metric)**: 동일한 라우팅 프로토콜 내부에서 복수의 경로가 존재할 때, 대역폭·지연·홉 수·비용 등을 종합하여 최적 경로를 판별하는 수치 척도.
- **제어 평면(Control Plane)과 데이터 평면(Data Plane)**: 경로 학습 및 라우팅 테이블(RIB)을 계산하는 제어 평면과 하드웨어 포워딩 테이블(FIB/TCAM)을 통해 패킷을 라인 레이트로 스위칭하는 데이터 평면의 분리 구조.

</details>

- **다중 출처 우선순위(AD)**: 동일 목적지에 대해 복수의 프로토콜이 경합 시 관리 거리(AD)가 가장 낮은 경로를 선별 (Connected 0 > Static 1 > OSPF 110 > BGP 20/200)
- **최적 비용 산출(Metric)**: 동일 프로토콜 내에서는 메트릭 비용(Cost)이 최소인 단일 또는 다중 경로(ECMP)를 최적 경로로 선택
- **제어 평면과 데이터 평면의 분리**: 소프트웨어 기반 **RIB** 에서 최적 경로를 산출한 후 하드웨어 ASIC 전용 **FIB(Forwarding Information Base)** 로 이관하여 고속 패킷 포워딩 달성

#### 한줄 요약
- 관리 거리(AD)와 메트릭으로 최적 경로를 선별하고, RIB/FIB 분리를 통해 고속 스위칭을 구현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **라우팅 정보 베이스(Routing Information Base, RIB)**: 모든 라우팅 프로세스로부터 수집된 후보 경로 정보 전체를 저장하고 최적 경로를 계산하는 제어 평면 소프트웨어 데이터베이스.
- **포워딩 정보 베이스(Forwarding Information Base, FIB)**: RIB에서 선별된 최적 활성 경로와 넥스트홉 MAC 주소를 매핑하여 하드웨어 TCAM에 적재한 데이터 평면 고속 룩업 테이블.
- **최장 프리픽스 일치(Longest Prefix Match, LPM)**: 수신 패킷의 목적지 IP와 FIB 엔트리를 대조할 때, 서브넷 마스크 비트 길이가 가장 길고 구체적인 엔트리를 우선 선택하는 규칙.

</details>

```text
[ 제어 평면 (Control Plane - CPU / RAM) ]
 ├─ [ 정적 경로 설정 (Static Route) ] ──────┐
 ├─ [ IGP 프로토콜 (OSPF / IS-IS) ] ─────────┼──▶ [ RIB (Routing Information Base) ]
 └─ [ EGP 프로토콜 (BGP) ] ──────────────────┘          │ (AD 및 Metric 비교 최적 경로 선별)
                                                        ▼
[ 데이터 평면 (Data Plane - ASIC / TCAM) ]
 [ 인입 패킷 (Ingress Packet) ] ──▶ [ FIB (LPM 룩업) ] ──▶ [ 송신 인터페이스 (Egress Next-Hop) ]
```

선의 의미: 다양한 라우팅 출처에서 수집된 정보가 RIB에서 통합 평가된 후, 최적 엔트리만 하드웨어 FIB로 복제되어 패킷 포워딩에 사용되는 파이프라인

| 구성요소 | 책임 | 저장 위치 및 매체 |
|:---|:---|:---|
| **관리 거리 (AD)** | 프로토콜 출처별 신뢰도 가중치를 부여하여 상이한 프로토콜 간 우선순위 결정 | 제어 평면 파라미터 |
| **메트릭 (Metric)** | 단일 프로토콜 내에서 경로의 물리적 비용(대역폭, 지연, 홉)을 계측 | 라우팅 알고리즘 |
| **RIB (Routing DB)** | 모든 후보 경로를 관리하고 최적 넥스트홉 경로를 산출하여 FIB로 동기화 | 시스템 메인 메모리(RAM) |
| **FIB (Forwarding DB)** | 목적지 IP 서브넷과 출력 포트/인접성(Adjacency)을 1:1 매핑하여 라인 레이트 룩업 수행 | TCAM / 고속 SRAM |
| **등가 다중 경로 (ECMP)** | 메트릭이 동일한 복수 경로에 대해 해시 기반 트래픽 로드 밸런싱 수행 | L4 해시 분배기 |

#### 한줄 요약
- AD와 메트릭, RIB 소프트웨어 테이블, FIB 하드웨어 룩업 엔진이 결합하여 L3 경로를 결정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인접성 테이블(Adjacency Table)**: L3 FIB의 넥스트홉 IP에 대응하는 L2 물리 MAC 주소 및 송신 포트 정보를 미리 확인(ARP 해석 완료)하여 보관하는 캐시 테이블.

</details>

```text
1. 라우팅 프로토콜(OSPF/BGP) 및 정적 설정으로부터 경로 정보 수집 ➔ RIB 적재
            │
            ▼
2. 관리 거리(AD) 및 메트릭 비교를 통한 최적 경로(Best Route) 선발
            │
            ▼
3. 최적 경로를 하드웨어 포워딩 테이블(FIB) 및 인접성 테이블(Adjacency)에 설치
            │
            ▼
4. 데이터 패킷 인입 시 TCAM 기반 최장 프리픽스 일치(LPM) 검색 ➔ 넥스트홉 포워딩
```

**동작 원리**

1. **경로 수집**: 정적 라우팅 엔트리와 동적 프로토콜의 라우팅 업데이트를 수신하여 RIB 구성
2. **최적 경로 판정**: 관리 거리(AD)가 가장 낮고, 메트릭이 최소인 경로를 활성 엔트리로 결정
3. **FIB 다운로드**: 제어 평면이 활성 경로를 데이터 평면의 TCAM 메모리에 프로그래밍
4. **LPM 하드웨어 스위칭**: 인입된 패킷의 목적지 IP에 대해 단일 클록 사이클 내에 최장 프리픽스를 검색하여 출력 포트로 전송

#### 한줄 요약
- RIB 경로 수집, 최적 경로 선발, FIB 하드웨어 적재, LPM 검색 및 포워딩 순으로 처리된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **수렴 시간(Convergence Time)**: 네트워크 토폴로지 변경(링크 단선 등) 발생 후, 모든 라우터가 변경된 경로 정보를 상호 교환하여 정합성 있는 새로운 라우팅 테이블을 완성할 때까지 소요되는 시간.

</details>

| 비교 항목 | 정적 라우팅 (Static Routing) | 동적 라우팅 (Dynamic Routing) |
|:---|:---|:---|
| **경로 설정 주체** | 네트워크 관리자가 CLI/API로 **수동 고정 설정** | 라우팅 프로토콜(OSPF, BGP)이 **자동 탐색 및 교환** |
| **토폴로지 변경 대응** | 링크 장애 시 관리자가 수정 전까지 **우회 불가** | 링크 단선 감지 시 새로운 경로로 **자동 수렴(Convergence)** |
| **라우터 자원 소모** | 라우팅 패킷 교환 부하 없음 (**CPU/RAM 극소화**) | 주기적 헬로 및 알고리즘 연산으로 **CPU/메모리 부하 발생** |
| **네트워크 규모** | 소규모망, 말단(Stub) 네트워크, 기본 게이트웨이 | 대규모 엔터프라이즈망, ISP 백본, 클라우드 데이터센터 |
| **보안성** | 경로 정보 브로드캐스트 부재로 **스푸핑에 안전** | 라우팅 프로토콜 패킷 암호화 인증(MD5/SHA) 요구 |

#### 한줄 요약
- 정적 라우팅은 자원 소모가 적고 단순하며, 동적 라우팅은 토폴로지 변경에 대한 자동 복원력을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IP SLA 및 경로 추적(IP SLA & Track)**: 정적 라우팅 설정 시 주기적으로 대상 IP에 ICMP 핑을 발송하여 회선 가용성을 감시하고, 응답 실패 시 정적 경로를 라우팅 테이블에서 자동 제거하는 헬스체크 기술.
- **경로 재분배(Route Redistribution)**: 서로 다른 라우팅 도메인(예: OSPF $\leftrightarrow$ BGP) 간에 경로 정보를 상호 주입하여 통신을 연동하는 기법.
- **비대칭 라우팅(Asymmetric Routing)**: 송신 트래픽과 수신 트래픽이 서로 다른 물리 경로를 통과하여 세션 기반 상태 추적 방화벽(Stateful Firewall)에서 패킷이 드롭되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정적 라우팅 설정 환경에서 원격 링크 단선 시 트래픽 블랙홀 발생 | **IP SLA 기반 프로브 감시 및 객체 추적(Track)** 연동 | 장애 감지 시 정적 경로 자동 회수 및 백업 경로 우회 |
| 이종 프로토콜 간 경로 재분배 시 상호 재주입으로 인한 라우팅 루프 | **경로 태그(Route Tag) 기반 필터링 및 Prefix-list** 적용 | 재분배된 경로의 역유입 차단 및 라우팅 안정성 확보 |
| 다중 경로 환경에서 비대칭 라우팅 발생 시 Stateful 방화벽 패킷 폐기 | 메트릭 조정을 통한 **대칭 경로(Symmetric Routing)** 강제 | 방화벽 세션 테이블 정합성 유지 및 비정상 패킷 드롭 방지 |

#### 한줄 요약
- IP SLA 트래킹으로 정적 경로 블랙홀을 방지하고, 경로 태그로 재분배 루프를 차단하며, 대칭 라우팅으로 방화벽 세션을 유지한다.

## Ⅶ. 결론

- 안정적인 네트워크 인프라 설계를 위해 엔터프라이즈 코어 및 백본 구간은 **동적 라우팅(OSPF/BGP)** 을 적용하여 고가용성 수렴을 보장하고, 말단(Stub) 세그먼트와 보안 경계 구간은 **IP SLA 추적 기능이 결합된 정적 라우팅(Floating Static)** 을 병행 구축하는 계층적 라우팅 아키텍처를 확립

#### 한줄 요약
- 동적 라우팅의 자동 수렴력과 정적 라우팅의 제어성을 결합하여 견고한 L3 인프라를 완성한다.
