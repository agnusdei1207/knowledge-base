## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MPLS(Multiprotocol Label Switching)**: 라우터가 매번 복잡한 IP 주소를 안 까보고, 패킷 겉면에 붙인 꼬리표(레이블) 숫자만 보고 빛의 속도로 던져버리는 2.5계층 꼼수 기술이다.
- **FEC(Forwarding Equivalence Class)**: "이 택배들은 다 부산 가는 거고 VIP 고객 거니까 하나로 묶어라" 하고 취급 방침이 똑같은 패킷들을 묶어놓은 그룹이다.
- **인터넷 프로토콜(IP)**: 32비트 목적지 주소로 네비게이션을 찍어주지만, 라우터가 매번 돋보기로 끝까지 확인해야 해서 CPU를 갉아먹는 구식 길 찾기 방식이다.
- **LSP(Label Switched Path)**: 입구에서 출구까지 레이블만 뗐다 붙였다(Swap) 하면서 터널처럼 일직선으로 뚫어놓은 전용 고속도로다.

</details>

- 정의: 복잡한 IP 주소 대신 꼬리표(레이블) 숫자만 보고 고속으로 패킷을 토스해 버리는 **2.5계층 스위칭 기술**
- 배경: 구식 IP 라우팅의 최단 경로 논리만으로는 고객별 전용선을 뚫어주거나(VPN) **트래픽을 우회시키는 비즈니스 통제가 불가능했기 때문**

#### 한줄 요약

- IP 주소 까볼 시간도 아까워서 택배 상자에 꼬리표를 붙이고 번호만 보고 던지는 초고속 배달 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **레이블 경계 라우터(LER)**: 망 입구에서 택배에 꼬리표를 딱 붙여주고(Push), 출구에선 꼬리표를 떼서(Pop) 원래 목적지로 던져주는 문지기 라우터다.
- **레이블 스위칭 라우터(LSR)**: 코어 망 한가운데서 IP는 쳐다보지도 않고, 들어온 꼬리표를 새 꼬리표로 바꿔치기(Swap)만 반복하는 무지성 고속 처리 기계다.
- **레이블 스택(Label Stack)**: "바깥쪽 꼬리표는 부산 가는 트럭용(LSP), 안쪽 꼬리표는 삼성전자 전용(VPN)" 이런 식으로 꼬리표를 여러 겹으로 겹쳐 발라서 서비스를 찢어버리는 사기 기술이다.

</details>

- 입출구 **레이블 경계 라우터(LER)** 에서 패킷을 FEC로 분류하고 꼬리표 뭉치인 **레이블 스택** 부착(Push/Pop).
- 가운데 낀 **레이블 스위칭 라우터(LSR)** 에서는 무겁게 IP 헤더를 까지 않고 단지 20비트 Label ID만 휙휙 교환(Swap)하여 하드웨어 스위칭 속도 극대화.
- **레이블 스택** 다중 꼬리표 구조를 통해 하나의 물리망에서 기업 간 VPN 트래픽을 완벽히 쪼개버리고(서비스 격리) 원하는 길로 트래픽을 비틀어버림(TE).

#### 한줄 요약

- 입구에서 꼬리표 붙이고(Push), 중간에선 번호표만 갈아 끼우며(Swap), 출구에서 뗀다(Pop).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레이블 전달 정보 기반(LFIB)**: 라우터 안에 "100번 꼬리표 달고 1번 포트로 들어오면, 200번 꼬리표로 덮어씌워서 2번 포트로 던져라"라고 구워놓은 초고속 컨닝 페이퍼다.

</details>

```text
[ MPLS 직관적 비교 기반 꼬리표 스위칭 구조 ]

[ 일반 인터넷 망 ]                                                 [ 일반 인터넷 망 ]
       │ (IP 패킷)                                                   ▲ (IP 패킷 복원)
       ▼                                                             │
┌────────────────┐         ┌────────────────────┐         ┌────────────────┐
│  [ 입구 LER ]  │         │  [ 코어 LSR ]      │         │  [ 출구 LER ]  │
│  (Label Push)  │ ──────▶ │  (Label Swap)      │ ──────▶ │  (Label Pop)   │
│  꼬리표 발라줌 │         │  꼬리표만 바꿔치기 │         │  꼬리표 떼버림 │
└────────────────┘         └────────────────────┘         └────────────────┘
       (LFIB 룩업)                 (LFIB 룩업)                   (LFIB 룩업)
```

| 구성요소 | 직관적 비교 책임 | 패킷 동작 |
|:---|:---|:---|
| **입구 LER (Ingress)** | IP 패킷 까보고 어디 갈지(FEC) 분류해서 **MPLS 꼬리표(Shim Header) 딱 붙여줌** | **Push** (레이블 삽입) |
| **코어 LSR (Transit)** | IP는 안 쳐다보고 LFIB 컨닝해서 **옛날 꼬리표 떼고 새 꼬리표로 갈아 끼움** | **Swap** (레이블 교환) |
| **출구 LER (Egress)** | **MPLS 꼬리표 다 떼버리고** 순수 오리지널 IP 패킷으로 원복해서 밖으로 던짐 | **Pop** (레이블 제거) |
| **PHP (출구 전 홉 장비)**| 출구 라우터 바쁠까봐, 바로 앞 장비가 눈치껏 미리 꼬리표 하나를 까주는 센스 | **Pop** (PHP 동작) |
| **MPLS Shim Header** | L2(MAC)와 L3(IP) 사이에 껴들어간 **32비트짜리 얇은 꼬리표 딱지 (2.5계층)** | Label ID(20비트) |

#### 한줄 요약

- 입출구 문지기(LER)가 꼬리표를 뗐다 붙였다 하고, 중간 일꾼(LSR)은 꼬리표 번호만 급격히 갈아치운다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **레이블 푸시(Label Push)**: 입구 문지기가 일반 IP 패킷 앞단에 32비트짜리 MPLS 꼬리표를 찰칵 하고 끼워 넣는 동작이다.
- **레이블 스왑(Label Swap)**: 가운데 일꾼이 LFIB 표를 보고 "100번 들어왔네? 200번으로 바꿔 달아!" 하고 꼬리표만 바꿔 치는 짓이다.
- **레이블 팝(Label Pop)**: 마지막 출구에서 "여기서부턴 꼬리표 필요 없어" 하고 껍데기를 확 벗겨서 원본 패킷만 내보내는 동작이다.

</details>

```text
[ MPLS 패킷 꼬리표 갈아 끼우기 십자포화 흐름 ]
┌──────────────────────────────┐
│ 0. IP 패킷 도착 (Dest: A)    │
│ (일반 인터넷망에서 유입됨)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. [입구 LER] Label Push     │
│ (분류해서 100번 꼬리표 붙임) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [코어 LSR] Label Swap     │
│ (100번 떼고 200번으로 바꿈)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [출구 앞 LSR] PHP Pop     │
│ (눈치껏 바깥 꼬리표 미리 뗌) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [출구 LER] 원본 복원      │
│ (남은 꼬리표 다 떼고 IP 쏨)  │
└──────────────────────────────┘
```

### 동작 원리

1. Label Push (입구 LER): 쌩 IP 패킷을 취급 방침(FEC)에 따라 꼬리표를 딱 붙임.
2. Label Swap (코어 LSR): LFIB 표를 보고 들어온 꼬리표를 다음 꼬리표로 교체함.
3. PHP Pop (출구 전 LSR): 출구 라우터가 IP 룩업에 집중하게 바깥 꼬리표를 하나 미리 까줌.
4. 원본 IP 전송 (출구 LER): 꼬리표를 완전히 떼버리고 원본 IP 패킷으로 목적지에 던짐.

#### 한줄 요약

- LER에서 꼬리표 달고(Push), LSR에서 꼬리표 바꾸고(Swap), 도착할 쯤 꼬리표 떼버린다(Pop).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **가상 사설망(VPN)**: 꼬리표 여러 개(레이블 스택)를 발라서, 물리적인 통신사 백본망 위에서 삼성전자 전용망과 LG전자 전용망이 서로 안 보이게 완벽히 찢어놓는 장사 밑천이다.

</details>

| 구분 | **MPLS 스위칭 (꼬리표 던지기)** | **일반 L3 IP 라우팅 (주소 까보기)** |
|:---|:---|:---|
| 포워딩 기준 | 딱 20비트 고정된 숫자인 **MPLS Label ID** 한정 보고 던짐 | 32비트 IP 주소를 끝까지 맞춰보는 LPM 룰 적용 |
| 패킷 룩업 위치 | L2와 L3 사이에 낑긴 **2.5 계층(Shim Header)** | 깊숙이 처박힌 **L3 IP 헤더 (20~60 바이트)** |
| 트래픽 엔지니어링 | 맘에 안 들면 강제로 우회시키는 **명시적 경로(TE) 쌉가능** | 무조건 메트릭 싼 최단 경로로만 몰빵해서 터짐 |
| 고가용성 방어 | 끊어지면 미리 파놓은 백업 길(FRR)로 **50ms 안에 절체됨** | 끊어지면 OSPF 다시 돌리느라 몇 초씩 멍때림 |

#### 한줄 요약

- 무식하게 최단 경로만 가는 IP 라우팅과 달리, MPLS는 꼬리표 장난으로 VPN도 뚫고 강제 우회도 시킨다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **LDP(레이블 분배 프로토콜)**: 라우터끼리 "이 IP 대역은 100번 꼬리표 쓰자" 하고 자동으로 번호판을 나눠 가지는 기본 프로토콜이다.
- **RSVP-TE(자원 예약 프로토콜)**: "이 VIP 트래픽은 저쪽 대역폭 넉넉한 우회도로로 가라" 하고 미리 터널(LSP)을 강제로 파놓는 고급 삽질 기술이다.
- **BFD(양방향 전달 탐지)**: 0.001초 단위로 "살아있냐?" 하고 핑을 때려서 끊기자마자 귀신같이 알아채는 초고속 감지 센서다.
- **FRR(Fast Reroute)**: BFD가 "길 끊어졌다!" 소리치면, 50ms(0.05초) 안에 미리 파놓은 백업 터널(RSVP-TE)로 트래픽을 확 돌려버리는 씹사기 복구 기술이다.
- **PMTU(경로 최대 전송 단위)**: 꼬리표(4바이트씩)를 겹쳐 붙이다 보면 기본 규격(1500)을 넘어 패킷이 깨지니까, 백본망 파이프(MTU) 크기를 점보 프레임으로 널널하게 뚫어주는 튜닝이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 꼬리표 겹쳐 발랐더니 1500바이트 넘어서 **패킷이 박살 나고 다 버려짐** | 백본 인터페이스 파이프(MTU)를 **점보 프레임(PMTU)으로 확장** | 꼬리표 붙인 뚱뚱한 패킷도 단편화 없이 쏙 통과 |
| 코어망 랜선 끊어졌는데 LDP가 멍때려서 **미디어/VoIP 세션 다 끊김** | **BFD** 센서 달고 **RSVP-TE FRR** 기반 0.05초 만에 백업 길로 꺾어버림 | 눈 깜짝할 새(50ms) 무중단 고속 우회 절체 완료 |
| A기업과 B기업이 사설 IP 똑같이(`192.168.x.x`) 쓰는데 통신사 백본에 **섞임** | 바깥 꼬리표 안에 **안쪽 꼬리표(VPN ID)** 까지 박는 다중 레이블 적용 | 회사 간 트래픽이 절대 안 섞이는 **서비스 격리** |

#### 한줄 요약

- 파이프 크기(MTU) 늘리고, BFD랑 FRR 엮어서 0.05초 안에 복구하고, 꼬리표 겹쳐서 남의 회사 못 보게 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **서비스 격리(Service Isolation)**: 다층 레이블 스택(꼬리표 겹쳐 바르기)을 활용해 하나의 통신사 물리 망에서 남의 회사 트래픽을 절대 엿볼 수 없게 찢어버리는 보안 기술이다.

</details>

- **서비스 격리** 원칙에 따라, VPN 격리는 **다층 레이블 스택**, 장애 대비는 **FRR** 적용하여 통신사급 무중단 백본을 설계하는 기조 확립함

#### 한줄 요약

- 통신사 밥줄인 MPLS는 레이블 떡칠로 고객망(VPN)을 찢어버리고, FRR로 랜선이 뽑혀도 통신을 살려낸다.
