## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCAM (삼진 내용 주소화 메모리)**: 일반 메모리처럼 주소 번호를 찾아서 들어가는 게 아니라, "이 IP 가진 놈 어딨어?" 하고 데이터를 던지면 모든 방을 한 번에 다 뒤져서 빛의 속도로 튀어나오는 개비싼 하드웨어 검색 칩이다. 삼진(Ternary)은 0, 1 말고 '무관(Don't Care, X)' 값까지 알아먹는다는 뜻이다.

</details>

- 정의: **TCAM** 라우터나 스위치가 패킷을 처리할 때, 수만 개의 라우팅 테이블이나 방화벽 규칙(ACL)을 단 한 번의 클럭(1 Clock) 만에 병렬로 싹 다 뒤져서 결과를 뽑아내는 초고속 검색 하드웨어다.
- 배경: 인터넷 트래픽이 미어발생하는데, CPU가 일반 메모리(RAM)를 1번부터 만 번까지 소프트웨어로 순차적으로 뒤지다간 패킷이 다 막혀서 지연(Delay)이 생기니까, **돈을 처부가하여라도 한 방에 다 뒤져주는 TCAM 칩을 네트워크 장비에 달게 되었다.** #### 한줄 요약

- 위에서부터 하나씩 읽는 뻘짓을 버리고, 수만 개의 규칙을 한 방에 동시에 찔러봐서 1초 만에 범인을 찾는 마법의 메모리다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우선순위 선택 (Priority Selection)**: 방화벽 룰을 짤 때 "10.0.0.0 대역은 차단해라", "근데 10.0.0.1은 허용해라" 두 개가 동시에 겹치면, 더 좁고 구체적이거나 순서가 높은 룰을 먼저 적용해 주는 지능형 선택 방식이다.

</details>

- **1-Clock 병렬 폭격 (하드웨어 검색)**: 수만 줄의 규칙이 있어도 소프트웨어처럼 위에서부터 하나씩 멍청하게 안 읽고, 하드웨어 회로가 수만 줄을 동시에 찔러봐서 1클럭 만에 답을 낸다.
- **무관(Don't Care, X) 마스킹**: 0과 1뿐만 아니라 "여긴 아무거나 와도 통과(X)"라는 마스크 처리가 가능해서, IP 서브넷 대역(10.0.0.X)이나 광범위한 접근 제어(ACL)를 찰떡같이 검색한다.
- **돈 먹는 하마 (전력/면적 폭발)**: 칩 안에 비교 회로를 무식하게 1:1로 다 집중 적용하여서, 일반 램(SRAM)보다 전기를 수십 배 처먹고 가격도 더럽게 비싸서 용량을 쥐꼬리만큼밖에 못 넣는다.

#### 한줄 요약

- 속도는 우주 최강이고 '아무거나(X)' 검색도 되지만, 가격이 비싸고 전기를 너무 많이 먹어서 용량이 늘 부족한 놈이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCAM 뱅크 (TCAM Bank)**: 비싼 TCAM을 막 쓰면 안 되니까, 라우팅용, 방화벽(ACL)용, QoS용 파티션을 나눠서 자기 영역만 쓰게 만들어 놓은 구역이다.
- **SRAM (동작 메모리)**: TCAM이 "야, 3번 룰에 걸렸어!" 하고 번호를 던져주면, SRAM이 "3번 룰은 패킷 버리는 거네(Drop)" 하고 진짜 할 일(Action)을 알려주는 단짝 메모리다.

</details>

```text
[ 초고속 하드웨어 검색 직관적 비교 구조 ]

[ 1. 검색 키 생성기 ] ── (들어온 패킷에서 목적지 IP나 포트 번호만 알맹이로 쏙 뽑아냄)
      │
      ▼
[ 2. TCAM 뱅크 ] ── (수만 개 룰에 동시에 찔러봄 $\to$ "어! 나 3번 룰이랑 7번 룰에 맞는데?")
      │
      ▼
[ 3. 우선순위 인코더 ] ── (3번이랑 7번 겹치네? 짬바 높은 3번 룰 채택!)
      │
      ▼
[ 4. 동작 SRAM ] ── (3번 룰 액션 꺼내옴 $\to$ "이 패킷은 엄격한 통제없이 폐기(Drop)해라!")
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **검색 키 생성기** | 패킷 헤더 까서 **비교할 IP, 포트 번호만 엑기스로 뽑아냄** | Key Generator |
| **TCAM 뱅크** | 알맹이 받아서 **수만 개 룰이랑 동시에 1:N으로 싹 다 대조해 봄** | TCAM Array |
| **우선순위 인코더** | 룰 여러 개 겹치면 **서열 제일 높은(최장 접두어) 놈 하나만 딱 고름** | Priority Encoder |
| **동작 SRAM** | TCAM이 번호표 주면 **"보내라, 버려라" 실제 액션(Action)값 꺼내줌** | Action RAM |

#### 한줄 요약

- TCAM이 수만 명 중에 얼굴을 한 번에 찾아내면, 단짝인 SRAM이 그놈을 어떻게 패야 할지(동작) 알려주는 콤비 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **일치 벡터 전달**: 모든 룰이랑 병렬 비교를 싹 돌린 다음, "저요! 저요!" 하고 조건에 맞는 룰들의 비트 벡터를 싹 다 뽑아주는 단계다.

</details>

```text
[ TCAM 1-Clock 검색 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [검색 키(Key) 생성 및 입력]
│ (시스템: 목적지 IP 10.1.1.5 들어왔다. TCAM에 던져!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [TCAM 전체 항목 병렬 폭격 비교]
│ (TCAM 뱅크: 1만 개 룰 전부 동시에 찔러봄)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [일치 벡터 및 최우선 인덱스 선택]
│ (인코더: 5번 룰, 12번 룰 겹치네. 5번이 더 구체적이니 5번 승리!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [SRAM 동작(Action) 인덱스 조회]
│ (SRAM: 5번 룰 액션 까보니까 '포워딩(Forward)'이네)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [패킷 최종 동작 집행]     │
│ (결과: 묻지도 따지지도 않고 해당 패킷 광속 포워딩 완료)
└──────────────────────────────┘
```

### 동작 원리

1. 키 생성: 스위치 칩셋이 패킷 헤더에서 소스/목적지 IP, 포트 등을 추출해 하나의 **검색 키** 기반 조합함.
2. TCAM 병렬 비교: 조합된 키를 TCAM 뱅크에 던지면, 칩 내의 전체 항목과 하드웨어적으로 **1-Clock 만에 일제히 비교**함.
3. 인코더 서열 정리: 조건이 맞는 룰이 여러 개 튀어나오면, **우선순위 인코더** 가장 상위 정책(최장 접두어 등) 하나를 픽함.
4. SRAM 동작 매핑: 픽된 룰의 주소(인덱스)를 **SRAM** 대상 던져서 '허용/차단/QoS 적용' 등의 실제 액션을 꺼내옴.
5. 집행: 스위치 ASIC 칩이 꺼내온 액션대로 패킷을 처리함.

#### 한줄 요약

- 키 뽑고 $\to$ TCAM에 던져 1초 만에 다 뒤진 뒤 $\to$ 제일 쎈 룰 하나 고르고 $\to$ SRAM에서 행동지침 꺼내 패는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAM (내용 주소화 메모리)**: 무관(X) 조건 그딴 거 없고, 오직 "이거랑 100% 똑같은 놈 어딨어?" 하고 0과 1만 정확히 일치하는 걸 찾는 2진 하드웨어 검색 칩이다.

</details>

| 구분 | **TCAM (비싸고 똑똑한 놈)** | **CAM (싸고 단순한 놈)** | **SRAM (메모리 국밥)** |
|:---|:---|:---|:---|
| 핵심 특징 | "10.0.0.X 다 잡아내!" **광역 수색대** | "10.0.0.1만 잡아내!" **점박이 정밀 탐지기** | 번호표 줘야 물건 찾아주는 **창고 비인가 작업자** |
| 처리 가능 데이터 | 0, 1, **X (무관/Don't Care)** 3가지 상태 | 0, 1 (정확히 똑같아야만 일치) | 주소(Address) 기반 순차 접근 |
| 주력 활용 분야 | **LPM(라우팅 최장일치), ACL(방화벽)**, QoS | **MAC 주소 테이블** (스위치 L2 포워딩) | TCAM 검색 후 **동작(Action) 저장용** |
| 치명적 한계 | 전기 과도하게 처먹고 가격이 **눈 튀어나오게 비쌈** | 범위(Subnet) 검색 불가능. 오직 정확 일치만 됨 | 규칙 1만 개면 1만 번 뒤져야 해서 **속도 현저한 지연** |

#### 한줄 요약

- 대역이나 범위를 퉁쳐서 검색할 땐 TCAM, MAC 주소처럼 핀포인트로 정확히 찾을 땐 CAM을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TCAM 고갈 (Exhaustion)**: 스위치에 비싼 TCAM 용량이 쥐꼬리만큼 들어있는데, 초보 관리자가 방화벽(ACL) 룰을 최적화 안 하고 무식하게 1만 줄씩 집중 적용하여서 메모리가 꽉 차버려 통신망 전체가 뻗어버리는 대규모 네트워크 장애다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 방화벽 룰 몇 줄 넣었더니 **TCAM 꽉 차서 스위치 뻗음** | 포트 범위(예: 포트 10~20) 규칙을 넣으면 멍청한 TCAM은 그걸 11줄로 쪼개서 저장해버림 (용량 폭발) | 범위 규칙 말고 **단일 규칙으로 묶거나 객체(Object) 그룹핑으로 룰 다이어트 빡세게 시킴** | 쥐꼬리만한 TCAM 메모리 아끼고 스위치 생명 연장 |
| 룰은 맞게 짰는데 **패킷이 안 막히고 그냥 통과됨** | 앞쪽 룰(허용)이 넓은 대역(10.0.0.X)을 잡아버려서 뒤쪽 구체적인 룰(차단)을 가려버림 (Shadowing) | 우선순위 인코더만 믿지 말고, **좁고 구체적인 룰을 맨 위로(Top) 올리게 순서 강제 재배치함** | 룰 씹히는 어이없는 오동작 막고 보안 정책 철저한 방어 |
| 라우팅 늘어나니까 **ACL 방화벽 룰이 안 들어감** | TCAM 뱅크 하나에 라우팅이랑 방화벽을 짬뽕으로 밀어 넣어서 용량 간섭 터짐 | 스위치 OS(SDM 템플릿 등)에서 **라우팅용, ACL용 TCAM 뱅크 파티션을 강제로 쪼개버림** | 한쪽이 꽉 차도 다른 기능에 피해 안 주고 망 안정성 챙김 |

#### 한줄 요약

- TCAM은 비싸고 좁으니까 룰 다이어트 빡세게 시키고, 넓은 룰이 좁은 룰 가리지 않게 순서 배치 똑바로 해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 폭발하는 인터넷 트래픽을 지연 없이 실시간 처리하기 위해, **0/1/X 삼진 마스킹** 및 **1-Clock 병렬 비교**, **우선순위 인코더** 활용 결합한 하드웨어 기반 TCAM 검색 기조 확립함

#### 한줄 요약

- TCAM은 비싸고 전기도 많이 먹지만, 현대 네트워크 장비가 미친 듯한 패킷 폭우 속에서도 뻗지 않게 버텨주는 궁극의 하드웨어 치트키다.
