## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCAM(Ternary Content Addressable Memory)**: 주소(Address)를 입력하여 데이터를 읽는 일반 RAM과 달리, 찾고자 하는 데이터(Key)를 입력하면 해당 데이터가 저장된 메모리 위치(Index)를 단일 클럭 사이클(1 Clock Cycle) 내에 병렬 검색하여 출력하는 고성능 연상 메모리.
- **삼진(Ternary) 상태**: 이진수 '0'과 '1' 외에 와일드카드 마스크인 **'무관(Don't Care, X)'** 상태를 추가 지원하여 비트 단위 마스킹 검색을 수행하는 특성.

</details>

- 정의/개념: L2/L3/L4 패킷 헤더 필드를 키(Key)로 입력받아 수만 개의 라우팅 테이블(LPM) 및 접근 제어 목록(ACL) 항목과 **1-클럭 동시 병렬 비교**를 수행하고, **우선순위 인코더(Priority Encoder)** 를 거쳐 포워딩 액션(SRAM)을 즉각 도출하는 **하드웨어 패킷 검색 가속 엔진**
- 배경/필요성: 100Gbps~400Gbps급 초고속 코어 라우터에서 소프트웨어 트리 탐색(Radix Tree) 방식의 $O(\log N)$ 지연 한계를 극복하고, 라인 레이트(Line-Rate) 패킷 스위칭을 달성할 요구

#### 한줄 요약
- 0, 1, X 삼진 마스킹을 지원하여 단일 클럭에 수만 개 규칙을 전병렬 검색하는 하드웨어 메모리이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최장 일치 접두어(Longest Prefix Match, LPM)**: 목적지 IP 주소가 복수의 서브넷 라우팅 규칙에 동시 매칭될 때 가장 긴(구체적인) 서브넷 마스크를 가진 경로를 최우선 선택하는 IP 라우팅 규칙.
- **우선순위 인코더(Priority Encoder)**: 다수의 TCAM 엔트리가 동시에 매칭(Match)되었을 때 메모리 상위 물리 주소(Lowest Numerical Index)를 갖는 단 하나의 최우선 결과만을 선택하여 인덱스를 출력하는 논리 회로.

</details>

- **결정론적 1-클럭 초고속 병렬 검색 ($O(1)$)**: 규칙 수의 증감에 무관하게 단 1클럭 내에 전체 엔트리 동시 비교 완료
- **비트 단위 와일드카드 마스킹 (0, 1, X)**: IP 서브넷(예: `/24`), L4 포트 범위, 프로토콜 마스크를 하드웨어 비트 레벨에서 완벽 지원
- **우선순위 기반 다중 매칭 해소**: 규칙 간 중복 매칭 시 우선순위 인코더를 통해 최우선 순위 정책 단일 선택

#### 한줄 요약
- $O(1)$ 1-클럭 검색, 비트 단위 X 마스킹, 우선순위 인코더 기반 다중 매칭 해소를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCAM 셀(Cell)**: 0과 1을 저장하는 2개의 SRAM 셀과 마스크 비교를 수행하는 비교 트랜지스터(통상 16T 구조)로 구성된 최소 물리 단위.
- **동작 SRAM(Associated Action RAM)**: TCAM이 출력한 매칭 인덱스를 물리 주소로 입력받아 해당 규칙의 실제 포워딩 액션(출력 포트, VLAN 태깅, 드롭 등)을 읽어내는 고속 메모리.

</details>

```text
[ 패킷 인입 (Header Extraction) ] ──▶ [ 검색 키 생성기 (Search Key Generator) ]
                                             │ (32bit IP / 104bit ACL Key)
                                             ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ TCAM 어레이 (Ternary Storage & Parallel Comparators) ]                 │
│  ├─ Entry 0: 192.168.1.0 / 24  ──▶ Match Line 0 ──┐                     │
│  ├─ Entry 1: 192.168.0.0 / 16  ──▶ Match Line 1 ──┼─▶ [ 우선순위 인코더 ]│
│  └─ Entry N: 0.0.0.0 / 0       ──▶ Match Line N ──┘   (최상위 인덱스 선택)│
└────────────────────────────────────────────────────────────────┬────────┘
                                                                 │ (선택된 Rule Index)
                                                                 ▼
[ 동작 메모리 (Action SRAM) ] ──────────────────────────────▶ [ 스위칭 패브릭 ]
 (Index에 매핑된 액션: "Port 3으로 포워딩", "Drop")             (라인 레이트 패킷 송출)
```

선의 의미: 검색 키가 TCAM 어레이 전체에 인가되어 병렬 비교된 후, 우선순위 인코더를 거쳐 동작 SRAM에서 최종 액션을 인출하는 파이프라인

| 구성요소 | 책임 및 역할 | 비고 |
|:---|:---|:---|
| **검색 키 생성기** | 패킷 헤더에서 IP, 포트, 프로토콜, MAC 필드를 파싱하여 정합된 키 벡터 생성 | Key Builder |
| **TCAM 어레이** | 데이터 비트와 마스크 비트를 저장하고 입력 키와의 일치 여부를 매치 라인(Match Line)으로 출력 | 16T 셀 구조 |
| **우선순위 인코더** | 복수의 매치 라인이 활성화되었을 때 가장 우선순위가 높은 엔트리의 인덱스 번호 선별 | Priority Resolver |
| **동작 SRAM** | 선택된 인덱스에 대응하는 포워딩 포트, 차단, DSCP 마킹 등의 액션 파라미터 반환 | Action Table |

#### 한줄 요약
- 검색 키 생성기, TCAM 어레이, 우선순위 인코더, 동작 SRAM이 결합하여 1클럭 내에 포워딩 결정을 내린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **매치 라인(Match Line)**: TCAM 엔트리의 모든 비트가 입력 키와 완벽히 일치할 때 전압이 High 상태를 유지하는 하드웨어 신호선.

</details>

```text
1. 스위치 ASIC 파서가 수신 패킷에서 L2~L4 헤더 필드 추출 ➔ 검색 키(Search Key) 구성
            │
            ▼
2. 검색 키를 TCAM 뱅크의 모든 엔트리 비교 회로에 동시 인가 (병렬 브로드캐스트)
            │
            ▼
3. 마스크(X) 비트를 제외한 모든 비트가 일치하는 엔트리들의 매치 라인(Match Line)이 동시 활성화
            │
            ▼
4. 우선순위 인코더가 활성화된 매치 라인 중 물리적 최우선 인덱스(Lowest Index)를 단일 선택
            │
            ▼
5. 선택된 인덱스를 주소로 Action SRAM을 조회 ➔ 포워딩 액션(출력 포트 지정)을 즉각 집행
```

**동작 원리**

1. **키 정합**: 패킷 헤더로부터 소스/목적지 IP 및 포트 번호를 묶어 표준 검색 키 포맷 구성
2. **전병렬 비교**: 사전 충전(Pre-charge)된 매치 라인 상에서 1클럭 동안 전체 엔트리 하드웨어 일괄 대조
3. **불일치 방전**: 단 1비트라도 불일치(Mismatch)하는 엔트리의 매치 라인은 접지로 방전(Discharge)
4. **다중 매칭 해소**: 복수의 매치 라인이 방전되지 않고 유지되면 우선순위 인코더가 최상위 룰 확정
5. **액션 파이프라인**: 인덱스에 매핑된 SRAM 엔트리에서 패킷 처리 지시자를 인출하여 전달

#### 한줄 요약
- 키 생성, 전병렬 비교, 매치 라인 판정, 우선순위 인코더 인덱스 선택, SRAM 액션 실행 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAM vs TCAM vs SRAM**: 0과 1만 비교하는 CAM, 0/1/X 삼진 마스킹을 지원하는 TCAM, 주소 기반 순차 탐색 SRAM의 비교.

</details>

| 비교 항목 | 삼진 메모리 (TCAM) | 2진 내용 주소화 메모리 (CAM) | 정적 램 (SRAM / DRAM) |
|:---|:---|:---|:---|
| **저장/비교 상태** | **0, 1, X (무관/Don't Care)** | **0, 1 (완전 일치만 지원)** | 0, 1 (데이터 저장 전용) |
| **검색 복잡도** | **$O(1)$ (1-Clock 전병렬 검색)** | **$O(1)$ (1-Clock 전병렬 검색)** | $O(\log N)$ (소프트웨어 트리 탐색) |
| **비트 셀 크기** | **대형 (~16 Transistors/cell)** | 중형 (~10 Transistors/cell) | **소형 (6 Transistors/cell)** |
| **소비 전력 및 발열**| **매우 높음 (모든 셀 동시 구동)** | 높음 | **낮음 (선택된 워드 라인만 구동)** |
| **주요 적용 분야** | **LPM 라우팅, ACL 방화벽, QoS** | **L2 이더넷 MAC 주소 테이블** | 일반 메모리, Action RAM |

#### 한줄 요약
- TCAM은 와일드카드 마스킹과 LPM 검색에 필수적이며, CAM은 MAC 매칭에, SRAM은 액션 데이터 저장에 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **범위 확장(Range Expansion)**: ACL에서 포트 범위(예: `Port 1024~65535`)를 지정할 때 TCAM의 비트 마스크 특성상 단일 엔트리로 표현하지 못하고 다수의 마스크 엔트리로 분할 적재되어 용량이 급증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| L4 포트 범위(Range) 설정 시 비트 마스킹 분할로 인한 TCAM 엔트리 폭증 (Range Expansion) | L4 포트 범위 비트 연산기(Range Matching Unit) 전용 하드웨어 및 **객체 그룹 집약** 적용 | 엔트리 소모량 80% 절감 및 TCAM 메모리 공간 보존 |
| 광범위한 서브넷 규칙이 구체적 규칙을 가려 정책이 무력화되는 **섀도잉(Shadowing) 발생** | ACL 컴파일러를 통한 **규칙 선별 정렬(Top-Down 정밀도 배치)** 및 구문 검증 | 보안 정책 씹힘 방지 및 의도된 화이트리스트 접근 통제 집행 |
| TCAM 자원 한계로 인한 라우팅 테이블(FIB) 또는 ACL 적재 실패 (TCAM 고갈) | **SDM(Switch Database Management) 템플릿 최적화** 및 알고리즈믹 TCAM(Tree+TCAM) 도입 | 기능별(Routing vs ACL) 최적 뱅크 파티셔닝 및 고갈 방지 |

#### 한줄 요약
- Range 매칭 최적화로 엔트리를 절감하고, 정밀도 순서 정렬로 섀도잉을 방지하며, SDM 템플릿으로 자원을 분할 관리한다.

## Ⅶ. 결론

- 테라비트급 스위치 및 라우터의 라인 레이트 패킷 처리를 위해 **0/1/X 삼진 마스킹 기반의 TCAM 하드웨어 아키텍처**는 필수 불가결한 핵심 기술이며, 높은 전력 소모와 하드웨어 면적 한계를 극복하기 위해 최신 데이터센터 스위치는 **SDM 템플릿 기반 자원 분할**, **알고리즈믹 TCAM(Algorithmic TCAM)** 및 **P4 프로그래머블 파이프라인**을 결합하여 고효율 패킷 포워딩을 완성

#### 한줄 요약
- TCAM의 1-클럭 전병렬 검색과 SDM 최적화를 통해 고성능 라인 레이트 스위칭을 구현한다.
