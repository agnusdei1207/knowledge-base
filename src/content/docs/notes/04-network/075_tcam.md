## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCAM (Ternary Content Addressable Memory)**: 데이터 키(Key)를 입력하면 0, 1, X(Don't Care) 삼진 마스크로 단 1클럭 내에 주소(Index)를 찾는 연상 메모리.
- **Ternary States (삼진 상태)**: 이진수 '0'과 '1' 외에 와일드카드 '무관(Don't Care, X)' 비트를 추가 지원하여 비트 단위 마스킹을 수행하는 특성.

</details>

- 정의/개념: 0·1·X 규칙을 **1클럭 전병렬 매칭**하는 검색 메모리
- 배경/필요성: 소프트웨어 트리 탐색은 규칙 수에 비례해 **메모리 접근을 반복**하여 라인 레이트를 지키지 못하므로, 전체 규칙을 1클록에 병렬 비교하는 삼진 검색 하드웨어를 포워딩 경로에 끼워 넣어 탐색 반복 자체를 제거

#### 한줄 요약
- **삼진 마스킹·전병렬 검색** 기반 라인 레이트 처리

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **LPM (Longest Prefix Match)**: 목적지 IP 주소와 가장 길게 일치하는 서브넷 마스크를 가진 라우팅 엔트리를 최우선 선택하는 IP 포워딩 알고리즘.
- **Priority Encoder (우선순위 인코더)**: 복수의 엔트리가 동시에 매칭되었을 때 가장 상위(Lowest Index)의 우선순위 인덱스를 단일 출력하는 하드웨어 회로.

</details>

- **1클럭 전병렬 검색**: 모든 엔트리의 일치 여부 동시 검출
- **LPM·와일드카드**: 가변 프리픽스와 ACL 마스크 지원
- **우선순위 인코더**: 동시 일치 중 최상위 엔트리 선택

#### 한줄 요약
- **전병렬 검색·와일드카드**와 우선순위 규칙 선별

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCAM Cell (16T)**: 데이터 비트와 마스크 비트를 저장하는 2개의 SRAM 셀 및 비교 트랜지스터(통상 16T)로 구성된 최소 물리 단위.
- **Associated Action RAM**: TCAM이 출력한 매칭 인덱스를 입력받아 실제 포워딩 액션(출력 포트, VLAN 등)을 인출하는 고속 SRAM.

</details>

```text
[TCAM 검색 구조]
|-- 검색 키 생성기
|-- TCAM 어레이
|-- 우선순위 인코더
`-- 동작 SRAM
```

선의 의미: 검색 키와 규칙·인덱스·동작의 정적 결합 관계

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| 검색 키 생성기 | 헤더를 파싱하여 **검색 키 벡터 생성** | Key Builder |
| TCAM 어레이 | 삼진 규칙 저장과 **매치 라인 출력** | 16T 셀 어레이 |
| 우선순위 인코더 | 복수 일치 중 **최우선 인덱스 선별** | Priority Resolver |
| 동작 SRAM | 인덱스에 대응하는 **동작 반환** | Action Table |

#### 한줄 요약
- TCAM 어레이는 일치 여부 판정만 맡고 실제 동작 값은 SRAM이 보관하므로, 비싼 삼진 셀은 검색 폭에만 쓰이고 결과 저장은 값싼 메모리가 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Match Line (매치 라인)**: 엔트리의 모든 비트가 입력 키와 일치할 때 전압이 High로 유지되는 하드웨어 감지 신호선.

</details>

```text
패킷 입력
    |
1. 헤더 파싱
    |
2. 전 엔트리 병렬 비교
    |
3. 매치 라인 판정
    |
4. 최우선 인덱스 선택
    |
5. 동작 SRAM 조회
    |
포워딩·차단 결과
```

- 1. 헤더 파싱
- 2. 전 엔트리 병렬 비교
- 3. 매치 라인 판정
- 4. 최우선 인덱스 선택
- 5. 동작 SRAM 조회

#### 한줄 요약
- 여러 규칙이 동시에 적중해도 우선순위 인코더가 1건으로 좁히므로, 규칙 수가 늘어날 때 늘어나는 대가는 조회 지연이 아니라 전력과 셀 면적이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCAM (0/1/X)** vs **CAM (0/1 완전 일치)** vs **SRAM (주소 기반 저장)**.

</details>

| 비교 항목 | 삼진 메모리 (TCAM) | 2진 내용 주소화 메모리 (CAM) | 정적 램 (SRAM / DRAM) |
|:---|:---|:---|:---|
| 저장/비교 상태 | **0, 1, X** | **0, 1 완전 일치** | 0, 1 데이터 저장 |
| 검색 복잡도 | **$O(1)$ 전병렬 검색** | **$O(1)$ 전병렬 검색** | $O(\log N)$ 트리 탐색 |
| 비트 셀 면적 | **대형, 약 16T** | 중형, 약 10T | **소형, 6T** |
| 소비 전력 및 발열 | **매우 높음** | 높음 | **낮음** |
| 주요 적용 분야 | **LPM·ACL·QoS** | **L2 MAC 테이블** | 일반 메모리·Action RAM |

#### 한줄 요약
- **TCAM은 LPM·ACL**, CAM은 MAC, SRAM은 동작 저장

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Range Expansion (범위 확장)**: L4 포트 범위(예: 1024~65535)를 비트 마스크로 변환할 때 다수의 엔트리로 분할 적재되어 용량이 낭비되는 현상.
- **SDM (Switch Database Management)**: 스위치의 사용 목적(라우팅 중심 vs ACL 보안 중심)에 따라 물리 TCAM 뱅크 비율을 동적으로 재분배하는 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| L4 포트 범위(Range) 설정 시 비트 마스킹 분할로 인한 **TCAM 엔트리 폭증** | **`L4 포트 범위 전용 연산기(Range Matching Unit)` 및 그룹화** | 엔트리 소모량 80% 절감 및 TCAM 메모리 보존 |
| 광범위한 서브넷 규칙이 구체적 규칙을 가려 정책이 무력화되는 **섀도잉(Shadowing)** | ACL 컴파일러를 통한 **`규칙 선별 정렬(Top-Down 정밀도 배치)`** | 보안 정책 누락 방지 및 정확한 화이트리스트 집행 |
| 라우팅 테이블(FIB) 또는 ACL 급증으로 인한 **TCAM 메모리 고갈** | **`SDM (Switch Database Management) 템플릿 최적화`** 적용 | 환경별(Routing vs ACL) 최적 뱅크 파티셔닝 |
| 전병렬 구동으로 인한 스위치 ASIC 전력 소모 및 발열 심화 | **`뱅크 분할 블록 활성화(Block-Select Gating)`** 저전력 설계 | 비활성 메모리 뱅크 전력 차단으로 전력 50% 절감 |

#### 한줄 요약
- Range 매칭 최적화, 정밀도 순서 정렬, SDM 템플릿 최적화, 뱅크 게이팅으로 운영한다.

## Ⅶ. 결론

- 대규모 LPM·ACL은 **TCAM**, 전력·용량 제약은 **SDM·알고리즈믹 TCAM** 선택

#### 한줄 요약
- **TCAM·SDM** 조합으로 검색 성능과 자원 효율 균형
