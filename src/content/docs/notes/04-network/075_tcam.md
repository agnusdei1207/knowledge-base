## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCAM (Ternary Content Addressable Memory)**: 데이터 키(Key)를 입력하면 0, 1, X(Don't Care) 삼진 마스크로 단 1클럭 내에 주소(Index)를 찾는 연상 메모리.
- **Ternary States (삼진 상태)**: 이진수 '0'과 '1' 외에 와일드카드 '무관(Don't Care, X)' 비트를 추가 지원하여 비트 단위 마스킹을 수행하는 특성.

</details>

- 정의/개념: 0, 1, X 삼진 마스크를 지원하여 수만 개의 라우팅(LPM) 및 ACL 규칙을 **1클럭($O(1)$) 내에 전병렬 매칭하는 하드웨어 패킷 검색 가속 엔진**
- 배경/필요성: 범용 메모리(SRAM/DRAM) 기반 소프트웨어 트리 탐색($O(\log N)$)의 한계로 인한 **메모리 접근 병목, 100Gbps+ 라인 레이트 포워딩 실패 및 지연 증가**

#### 한줄 요약
- 0/1/X 삼진 마스킹과 1-Clock 전병렬 검색을 통해 테라비트급 라인 레이트 패킷 처리를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **LPM (Longest Prefix Match)**: 목적지 IP 주소와 가장 길게 일치하는 서브넷 마스크를 가진 라우팅 엔트리를 최우선 선택하는 IP 포워딩 알고리즘.
- **Priority Encoder (우선순위 인코더)**: 복수의 엔트리가 동시에 매칭되었을 때 가장 상위(Lowest Index)의 우선순위 인덱스를 단일 출력하는 하드웨어 회로.

</details>

- **1-Clock 전병렬 검색($O(1)$ 복잡도)**: 모든 저장 엔트리의 비교기가 동시에 구동되어 **단일 클럭 사이클 내에 일치 엔트리 검출**
- **최장 일치(LPM) 및 와일드카드 마스킹**: 가변 길이 서브넷 마스크 및 ACL 와일드카드 마스크를 하드웨어 비트 레벨에서 완벽 지원
- **우선순위 인코더 기반 다중 매칭 해소**: 복수 규칙이 동시 일치 시 **우선순위가 가장 높은 최상위 엔트리 단일 선택**

#### 한줄 요약
- 1-Clock 전병렬 검색($O(1)$), 0/1/X 와일드카드 마스킹, 우선순위 인코더 기반 최상위 규칙 선별을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCAM Cell (16T)**: 데이터 비트와 마스크 비트를 저장하는 2개의 SRAM 셀 및 비교 트랜지스터(통상 16T)로 구성된 최소 물리 단위.
- **Associated Action RAM**: TCAM이 출력한 매칭 인덱스를 입력받아 실제 포워딩 액션(출력 포트, VLAN 등)을 인출하는 고속 SRAM.

</details>

```text
[TCAM 하드웨어 아키텍처 및 액션 SRAM 파이프라인]
|-- Header Parser (L2~L4 헤더 필드 추출 -> 104bit ACL / 32bit IP 검색 키 생성)
`-- TCAM Array (Ternary Storage & 1-Clock Parallel Comparators)
|   |-- Entry 0: 192.168.1.0/24 (Match Line 0) ──┐
|   |-- Entry 1: 192.168.0.0/16 (Match Line 1) ──┼─▶ [ Priority Encoder ] (최상위 Rule Index 확정)
|   `-- Entry N: 0.0.0.0/0      (Match Line N) ──┘
`-- Associated Action SRAM (선택된 Index를 주소로 조회 -> "Port 3 Forward", "Drop" 액션 실행)
```

선의 의미: 검색 키가 TCAM 어레이 전체에 인가되어 병렬 비교된 후 우선순위 인코더를 거쳐 동작 SRAM에서 최종 액션을 인출하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **검색 키 생성기** | 패킷 헤더에서 IP, 포트, 프로토콜, MAC을 파싱하여 **정합된 검색 키 벡터 생성** | Key Builder |
| **TCAM 어레이** | 데이터와 마스크 비트를 저장하고 **입력 키와의 일치 여부를 매치 라인으로 출력** | 16T 셀 어레이 |
| **우선순위 인코더** | 복수의 매치 라인이 활성화되었을 때 **최우선 엔트리의 인덱스 번호 선별** | Priority Resolver |
| **동작 SRAM** | 선택된 인덱스에 대응하는 **포워딩 포트, 차단, DSCP 마킹 등의 액션 파라미터 반환** | Action Table |

#### 한줄 요약
- 검색 키 생성기, TCAM 어레이, 우선순위 인코더, 동작 SRAM이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Match Line (매치 라인)**: 엔트리의 모든 비트가 입력 키와 일치할 때 전압이 High로 유지되는 하드웨어 감지 신호선.

</details>

```text
TCAM 전병렬 검색 및 포워딩 액션 집행 파이프라인
        │
   1. [헤더 파싱 및 키 생성] 스위치 ASIC이 수신 패킷 헤더에서 L2~L4 필드를 추출하여 검색 키 구성
        │
   2. [전 엔트리 병렬 인가] 생성된 검색 키를 TCAM 뱅크의 모든 엔트리 비교 회로에 동시 인가
        │
   3. [매치 라인 전압 평가] 마스크(X) 비트를 제외한 모든 비트가 일치하는 엔트리 매치 라인 활성화
        │
   4. [우선순위 인코딩] 우선순위 인코더가 활성화된 매치 라인 중 최우선 인덱스(Lowest Index) 선택
        │
   ▼
5. [액션 SRAM 조회 및 집행] 선택된 인덱스로 Action SRAM을 조회하여 출력 포트 포워딩 즉각 실행
```

#### 한줄 요약
- 키 생성 → 전병렬 비교 → 매치 라인 판정 → 우선순위 인코더 인덱스 선택 → SRAM 액션 실행 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCAM (0/1/X)** vs **CAM (0/1 완전 일치)** vs **SRAM (주소 기반 저장)**.

</details>

| 비교 항목 | 삼진 메모리 (TCAM) | 2진 내용 주소화 메모리 (CAM) | 정적 램 (SRAM / DRAM) |
|:---|:---|:---|:---|
| **저장/비교 상태** | **0, 1, X (무관/Don't Care)** | **0, 1 (완전 일치만 지원)** | 0, 1 (데이터 저장 전용) |
| **검색 복잡도** | **$O(1)$ (1-Clock 전병렬 검색)** | **$O(1)$ (1-Clock 전병렬 검색)** | $O(\log N)$ (소프트웨어 트리 탐색) |
| **비트 셀 면적** | **대형 (~16 Transistors/cell)** | 중형 (~10 Transistors/cell) | **소형 (6 Transistors/cell)** |
| **소비 전력 및 발열**| **매우 높음 (전체 셀 동시 구동)**| 높음 | **낮음 (선택 워드 라인만 구동)**|
| **주요 적용 분야** | **LPM 라우팅, ACL 방화벽, QoS** | **L2 이더넷 MAC 주소 테이블** | 일반 메모리, Action RAM |

#### 한줄 요약
- TCAM은 와일드카드 마스킹과 LPM 검색에 필수적이며, CAM은 MAC 매칭에, SRAM은 액션 데이터 저장에 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Range Expansion (범위 확장)**: L4 포트 범위(예: 1024~65535)를 비트 마스크로 변환할 때 다수의 엔트리로 분할 적재되어 용량이 낭비되는 현상.
- **SDM (Switch Database Management)**: 스위치의 사용 목적(라우팅 중심 vs ACL 보안 중심)에 따라 물리 TCAM 뱅크 비율을 동적으로 재분배하는 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| L4 포트 범위(Range) 설정 시 비트 마스킹 분할로 인한 **TCAM 엔트리 폭증** | **`L4 포트 범위 전용 연산기(Range Matching Unit)` 및 그룹화** | 엔트리 소모량 80% 절감 및 TCAM 메모리 보존 |
| 광범위한 서브넷 규칙이 구체적 규칙을 가려 정책이 무력화되는 **섀도잉(Shadowing)** | ACL 컴파일러를 통한 **`규칙 선별 정렬(Top-Down 정밀도 배치)`** | 보안 정책 누락 방지 및 정확한 화이트리스트 집행 |
| 라우팅 테이블(FIB) 또는 ACL 급증으로 인한 **TCAM 메모리 고갈** | **`SDM (Switch Database Management) 템플릿 최적화`** 적용 | 환경별(Routing vs ACL) 최적 뱅크 파티셔닝 |
| 전병렬 구동으로 인한 스위치 ASIC 전력 소모 및 발열 심화 | **`뱅크 분할 블록 활성화(Block-Select Gating)`** 저전력 설계 | 비활성 메모리 뱅크 전력 차단으로 전력 50% 절감 |

#### 한줄 요약
- Range 매칭 최적화, 정밀도 순서 정렬, SDM 템플릿 최적화, 뱅크 게이팅으로 운영한다.

## Ⅶ. 결론

- 테라비트급 스위치 및 라우터의 라인 레이트 패킷 처리를 위해 **0/1/X 삼진 마스킹 기반의 TCAM 하드웨어 아키텍처는 필수 기술**이며, 높은 전력 소모와 면적 한계를 극복하기 위해 최신 데이터센터 스위치는 **SDM 템플릿 기반 자원 분할, 알고리즈믹 TCAM, P4 프로그래머블 파이프라인**을 결합하여 고효율 패킷 포워딩 완성

#### 한줄 요약
- TCAM은 0/1/X 삼진 마스킹과 1-Clock 전병렬 검색을 통해 테라비트급 고속 패킷 스위칭을 실현하는 핵심 하드웨어 메모리다.
