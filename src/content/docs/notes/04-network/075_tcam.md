## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **삼진 내용 주소화 메모리(Ternary Content-Addressable Memory, TCAM)**: 입력 키를 0•1•무관 값으로 저장된 모든 규칙과 동시에 비교하는 병렬 검색 메모리이다.

</details>

- 정의/개념: 0•1•무관 조건을 모든 항목과 비교하는 **TCAM**이다.
- 배경/필요성: 순차 메모리는 규칙 수가 늘수록 조회 지연이 커진다.

#### 한줄 요약

- 모든 규칙을 한꺼번에 비교하고 무관 값으로 주소 범위까지 표현해 가장 앞선 규칙을 찾는다.

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **우선순위 선택**: 여러 규칙이 동시에 일치할 때 정책 순서가 가장 높은 항목의 동작을 고르는 방식이다.

</details>

- **우선순위 선택**: 복수 일치 중 최상위 규칙을 결정한다.

#### 한줄 요약

- 검색은 빠르지만 모든 항목을 동시에 비교해 전력과 면적 비용이 크므로 규칙 수를 아껴야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **TCAM 뱅크**: 경로•접근 제어 목록•서비스 품질 등 검색 기능이나 키 폭에 따라 값•마스크•유효 비트 항목을 나눈 하드웨어 영역이다.
- **정적 임의 접근 메모리(Static Random-Access Memory, SRAM)**: 주소 기반으로 데이터와 동작을 저장하는 메모리이다.

</details>

**TCAM**이 규칙을 비교하고 **SRAM**이 대응 동작을 저장한다.

```text
TCAM 검색 구조
├─ 검색 키 생성기
├─ TCAM 뱅크
├─ 우선순위 인코더
├─ 동작 SRAM
└─ 규칙 관리자
```

선의 의미: 가로선은 검색 키, TCAM 규칙, 우선순위 선택과 대응 동작 저장소의 정적 결합 관계이고, 위 가지는 규칙 관리자가 TCAM 뱅크와 동작 SRAM의 영역•규칙을 함께 관리하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 검색 키 생성기 | 패킷 헤더•비교 필드 결합 |
| TCAM 뱅크 | 값•마스크•유효 비트 병렬 비교 |
| 우선순위 인코더 | 최우선 일치 인덱스 선택 |
| 동작 SRAM | 전달•폐기•재표시 동작 저장 |
| 규칙 관리자 | 영역•우선순위•사용량 관리 |

#### 한줄 요약

- 모든 규칙을 병렬 비교한 뒤 우선순위 인코더가 가장 앞선 규칙의 동작을 SRAM에서 찾는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **일치 벡터 전달**: 모든 값•마스크 항목의 병렬 비교 결과를 비트 벡터로 제공하는 단계이다.
- **최우선 인덱스 선택**: 동시에 일치한 항목 중 정책 우선순위가 가장 높은 위치를 고르는 단계이다.
- **동작 인덱스 조회**: 선택한 위치에 대응하는 전달•폐기•재표시 동작을 정적 임의 접근 메모리에서 읽는 단계이다.

</details>

```text
검색 키 입력
      │
      ▼
TCAM 전체 항목 병렬 비교
      │
      ▼
1. 일치 벡터 전달
      │
      ▼
2. 최우선 인덱스 선택
      │
      ▼
3. 동작 인덱스 조회
      │
      ▼
패킷 동작 반환
```

### 동작 원리

1. **일치 벡터 전달**: **일치 벡터 전달** 단계에서 모든 값•마스크 항목을 병렬 비교한다.
2. **최우선 인덱스 선택**: **최우선 인덱스 선택** 단계에서 가장 높은 우선순위 일치를 결정한다.
3. **동작 인덱스 조회**: **동작 인덱스 조회** 단계에서 **SRAM**의 전달•폐기•재표시 동작을 검색한다.

#### 한줄 요약

- 여러 규칙이 동시에 일치하므로 우선순위가 잘못되면 의도와 다른 동작이 실행된다.

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **내용 주소화 메모리(Content-Addressable Memory, CAM)**: 저장된 모든 값과 입력 키를 병렬로 정확 비교하는 메모리이다.
- **최장 접두어 일치(Longest Prefix Match, LPM)**: 가장 긴 접두어가 일치하는 경로를 선택하는 방식이다.
- **접근 제어 목록(Access Control List, ACL)**: 패킷 조건별 허용•차단 규칙 목록이다.
- **서비스 품질(Quality of Service, QoS)**: 트래픽 등급별 자원을 차등 적용하는 체계이다.
- **매체 접근 제어(Media Access Control, MAC)**: 공유 매체 접근과 프레임 전달을 제어하는 계층이다.

</details>

| 검색 메모리 비교 | TCAM | CAM | SRAM•해시 |
|:---|:---|:---|:---|
| 적용 기준 | **LPM**•**ACL**•**QoS** 우선순위 | **MAC** 등 정확 일치 | 대용량 세션•동작 정보 |
| 핵심 특징 | **TCAM**의 0•1•X 병렬 마스크 일치 | **CAM**의 0•1 병렬 정확 일치 | 주소•해시 기반 정확 조회 |
| 한계 | 전력•비용•규칙 확장 | 마스크 범위 표현 불가 | 충돌•다단 조회 지연 |

> 요약: 정확 일치는 CAM, 마스크 검색은 TCAM이다.

#### 한줄 요약

- TCAM이 일치하면 SRAM이 대응 동작을 제공하는 것이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **TCAM 고갈**: 특정 기능의 규칙 확장이 한정된 병렬 검색 항목을 점유해 다른 경로•보안•QoS 정책을 수용하지 못하는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 한 기능의 규칙 증가로 **TCAM 고갈** | **TCAM 뱅크**를 경로•ACL•QoS 영역에 할당 | 자원 간섭 방지 |
| 범위 규칙의 확장량을 과소 산정 | 마스크 전개 후 항목 수 계산 | 용량 예측 정확성 향상 |
| 앞선 규칙이 뒤 규칙을 항상 가림 | 중복•포함 관계 사전 분석 | 정책 오동작 방지 |

#### 한줄 요약

- 경로•ACL•QoS 규칙에 TCAM 영역을 나눠 한 기능의 규칙 증가가 다른 기능의 하드웨어 검색 공간을 고갈시키지 않게 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **검색 메모리 선택**: 규칙의 마스크•우선순위•정확 일치 요구와 용량을 기준으로 삼진•내용 주소화•정적 임의 접근 메모리를 결정하는 기준이다.

</details>

- **검색 메모리 선택**에서 범위•우선순위는 **TCAM**, 정확 일치는 **CAM**, 대용량 세션은 **SRAM**•해시가 핵심이다.

#### 한줄 요약

- 범위•우선순위 검색이 필요한 규칙만 TCAM에 두고 늘어나는 항목 수를 먼저 계산해야 한다.
