## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCP/IP 4계층 모델**: 인터넷 표준 프로토콜 스위트(Suite)의 통신 기능을 응용(L4), 전송(L3), 인터넷(L2), 네트워크 접근(L1)의 4개 계층으로 구조화한 사실상(De facto) 표준 네트워크 참조 모델.
- **전송 제어 프로토콜(TCP)**: 흐름 제어, 혼잡 제어 및 3-Way Handshake를 통해 신뢰성 있는 연결 지향적 바이트 스트림 전송을 보장하는 L4 계층 프로토콜.
- **인터넷 프로토콜(IP)**: 패킷의 논리적 주소 지정(Addressing)과 경로 배정(Routing)을 담당하며 비연결형 최선형(Best-Effort) 전달을 수행하는 L3 계층 핵심 프로토콜.

</details>

- 정의/개념: 분산된 이기종 컴퓨터망을 상호 연결하기 위해 IP 계층을 중심으로 프로토콜 계층을 실용화한 **인터넷 표준 네트워크 아키텍처(TCP/IP 4-Layer Model)**
- 배경/필요성: 초기 독점 통신 벤더 간 프로토콜 비호환성을 극복하고, 개방형 인터페이스 표준화를 통해 전 세계 네트워크의 확장성과 상호운용성을 확보할 요구

#### 한줄 요약
- 응용, 전송, 인터넷, 네트워크 접근의 4계층으로 인터넷 통신 표준 인터페이스를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **모래시계 구조(Thin-Waist Architecture)**: 상위의 다양한 응용 서비스(HTTP, DNS 등)와 하위의 이기종 물리 매체(Ethernet, Wi-Fi, 5G 등)가 오직 단일 IP 계층만을 통해 연결되는 확장성 중심 설계 구조.
- **종단 간 원칙(End-to-End Principle)**: 네트워크 내부 라우터는 단순 패킷 전달(Routing)에만 집중하고, 데이터 무결성 검증 및 재전송 제어 등의 지능적 상태 관리는 양 끝단 호스트(End-Host)가 전담한다는 네트워크 설계 철학.
- **최선형 전달(Best-Effort Delivery)**: IP 계층에서 패킷의 신뢰성이나 전송 지연을 보장하지 않는 대신, 네트워크 제어 오버헤드를 최소화하여 라우팅 처리량을 극대화하는 방식.

</details>

- **모래시계 구조(Thin-Waist)**: 상위 응용 계층과 하위 물리 전송 기술 간의 종속성을 제거하고 IP 계층으로 통합 인터페이싱
- **종단 간 원칙(End-to-End)**: 중간 네트워크 노드의 상태(State) 유지를 배제하여 코어 라우터의 처리 성능 및 망 확장성 보장
- **계층별 독립성 및 캡슐화**: 상위 데이터에 헤더를 부착(Encapsulation)하여 계층 간 인터페이스를 추상화하고 독립적 모듈 진화 지원

#### 한줄 요약
- Thin-Waist 모래시계 구조, 종단 간 원칙, Best-Effort 전달을 통해 전역 확장성을 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포트 번호(Port Number)**: 호스트 내에서 실행 중인 특정 프로세스/응용 프로그램을 식별하는 16비트 전송 계층 식별자.
- **MAC 주소(MAC Address)**: 데이터링크 계층(L2)에서 동일 로컬 링크 세그먼트 내 노드 간 프레임 전송을 위해 네트워크 인터페이스 카드(NIC)에 부여된 48비트 하드웨어 식별자.

</details>

```text
[ TCP/IP 4계층 및 PDU 캡슐화 구조 ]

 ┌───────────────────────────────────────────────────────────┐
 │ L4. 응용 계층 (Application) ──▶ 데이터 (Data / Message)   │  (HTTP, DNS, TLS)
 ├───────────────────────────────────────────────────────────┤
 │ L3. 전송 계층 (Transport) ────▶ 세그먼트 (Segment)        │  (TCP: 포트번호, 순서/ACK)
 ├───────────────────────────────────────────────────────────┤
 │ L2. 인터넷 계층 (Internet) ───▶ 패킷 / 데이터그램 (Packet)│  (IP: 논리 IP 주소, 라우팅)
 ├───────────────────────────────────────────────────────────┤
 │ L1. 네트워크 접근 (Network) ──▶ 프레임 (Frame / Bit)      │  (Ethernet, Wi-Fi: MAC 주소)
 └───────────────────────────────────────────────────────────┘
```

선의 의미: 상위 계층에서 하위 계층으로 내려가며 프로토콜 제어 헤더가 순차적으로 부착되는 계층 캡슐화 구조

| 구성요소 | 책임 | 대표 프로토콜 및 식별자 |
|:---|:---|:---|
| **L4 응용 계층 (Application)** | 사용자 인터페이스, 데이터 표현 및 세션 제어를 통합 수행하여 서비스 로직 제공 | HTTP, HTTPS, DNS, SSH |
| **L3 전송 계층 (Transport)** | 종단 프로세스 간 신뢰성 제어(TCP) 또는 고속 비연결 전송(UDP) 및 다중화 수행 | TCP, UDP (16비트 포트 번호) |
| **L2 인터넷 계층 (Internet)** | 논리 주소 기반 호스트 식별, 최적 경로 결정(Routing) 및 패킷 단편화 제어 | IP, ICMP, ARP (32/128비트 IP 주소) |
| **L1 네트워크 접근 (Network Access)**| 인접 노드 간 프레임 동기화, 오류 검출(CRC) 및 물리 전자기 신호 변환 | Ethernet, Wi-Fi (48비트 MAC 주소) |

#### 한줄 요약
- 응용(Data), 전송(Segment), 인터넷(Packet), 네트워크 접근(Frame) 계층이 상호 유기적으로 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캡슐화(Encapsulation)**: 송신 측에서 상위 계층 데이터에 하위 프로토콜 헤더를 순차적으로 덧붙여 전송 단위(PDU)를 구성하는 과정.
- **역캡슐화(Decapsulation)**: 수신 측에서 하위 계층 헤더를 순차적으로 검증 및 파싱하여 제거하고 최종 상위 데이터만 응용 계층으로 전달하는 과정.

</details>

```text
[ 송신 호스트 (캡슐화 파이프라인) ]
 1. 응용 데이터 생성 ➔ 2. L4 TCP 헤더(Port) 부착 ➔ 3. L3 IP 헤더 부착 ➔ 4. L2 MAC 헤더/FCS 부착
                                                                                      │
                                                                                      ▼ (물리 신호)
 [ 중간 라우터 : L2/L3 계층만 파싱하여 IP 목적지 라우팅 수행 ] ─────────────────────────┘
                                                                                      │
                                                                                      ▼
[ 수신 호스트 (역캡슐화 파이프라인) ]
 1. 응용 데이터 전달 ◀─ 2. L4 포트 디멀티플렉싱 ◀─ 3. L3 IP 검증 ◀─ 4. L2 MAC/CRC 검증
```

**동작 원리**

1. **응용 메시지 생성**: 브라우저 등 사용자 프로세스가 응용 페이로드 생성
2. **전송 세그먼트화**: TCP가 포트 번호, 시퀀스 번호(SEQ) 헤더를 부착하여 세그먼트 생성
3. **네트워크 패킷화**: IP 계층이 출발지/목적지 IP 주소와 TTL을 포함한 IP 헤더 추가
4. **링크 프레임화**: 네트워크 인터페이스가 대상 넥스트홉 MAC 주소와 오류 검출 FCS를 부착하여 전송
5. **종단 역캡슐화**: 수신단에서 L2 $\rightarrow$ L3 $\rightarrow$ L4 순으로 헤더 유효성을 검증하고 해당 포트의 프로세스로 데이터 인계

#### 한줄 요약
- 송신단 캡슐화, 라우터 L3 포워딩, 수신단 역캡슐화 파이프라인을 거쳐 데이터가 종단 간 전달된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OSI 7계층 모델**: ISO에서 정의한 이론적 통신 참조 모델로, 세션 계층(L5)과 표현 계층(L6)을 독립 계층으로 분리 규정한 학술 표준.

</details>

| 비교 항목 | TCP/IP 4계층 모델 | OSI 7계층 모델 |
|:---|:---|:---|
| **모델 성격** | 실제 인터넷 구현 기반 **사실상 표준(De facto)** | 통신 시스템 설계를 위한 **국제 표준 참조 모델(De jure)** |
| **계층 수** | **4개 계층** (L4, L3, L2, L1) | **7개 계층** (L7, L6, L5, L4, L3, L2, L1) |
| **세션/표현 계층** | **응용 계층(L4) 내 소프트웨어 라이브러리로 통합** | 세션(L5), 표현(L6) 독립 계층 분리 |
| **데이터링크/물리** | **네트워크 접근 계층(L1)으로 통합** | 데이터링크(L2), 물리(L1) 분리 |
| **신뢰성 제어 책임** | **종단 호스트(L4 TCP)에 집중 위임** | 각 계층별 분산 오류 제어 지향 |

#### 한줄 요약
- TCP/IP는 구현 중심의 4계층 구조이며, OSI는 개념적 참조를 위한 7계층 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최대 세그먼트 크기(Maximum Segment Size, MSS)**: TCP 계층에서 IP 및 TCP 헤더 오버헤드를 제외하고 단일 패킷에 실을 수 있는 최대 사용자 데이터 바이트 크기.
- **MSS 클램핑(MSS Clamping)**: 터널링(IPsec, GRE) 헤더 추가로 인해 MTU 초과 단편화가 발생하는 것을 방지하기 위해 TCP 핸드셰이크 SYN 패킷 내 MSS 값을 강제로 낮추어 변환하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 터널링(VPN/VXLAN) 오버헤드로 인한 MTU 초과 및 IP 단편화 지연 | 라우터/방화벽에 **TCP MSS 클램핑(MSS Clamping)** 및 Path MTU Discovery 적용 | 패킷 단편화 방지 및 VPN 터널 전송 처리량 최적화 |
| 실시간 미디어 전송 시 TCP 재전송 및 혼잡 제어로 인한 버퍼링 지연 | 실시간 음성/영상 트래픽에 **UDP 기반 RTP/SRTP** 및 **QUIC 프로토콜** 적용 | 연결 설정 오버헤드 제거 및 저지연 스트리밍 보장 |
| 복합 네트워크 장애 발생 시 문제 원인 구간 파악 지연 | L1(물리 링크) $\rightarrow$ L2(ARP/VLAN) $\rightarrow$ L3(IP/라우팅) $\rightarrow$ L4(포트) **상향식(Bottom-Up) 진단** 체계화 | 문제 식별 경로 단축 및 평균 복구 시간(MTTR) 단축 |

#### 한줄 요약
- MSS 클램핑으로 단편화를 방지하고, QUIC/UDP로 실시간성을 확보하며, 상향식 계층 진단으로 장애를 신속 복구한다.

## Ⅶ. 결론

- 글로벌 표준 네트워크 통신은 **TCP/IP 4계층 모델**의 **Thin-Waist(IP) 아키텍처**와 **종단 간 원칙(End-to-End)** 을 기반으로 시스템을 구현하되, 통신 장애 진단 및 시스템 아키텍처 설계 명세화 시에는 **OSI 7계층 모델**의 계층 분리 원칙을 병행 매핑하여 네트워크 운영 신뢰성과 확장성을 동시에 확보

#### 한줄 요약
- 구현과 운영은 실용적 TCP/IP 4계층으로 완성하고 진단과 표준화는 OSI 7계층을 매핑한다.
