## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCP/IP 4-Layer Model**: 인터넷 통신 기능을 응용(L4), 전송(L3), 인터넷(L2), 네트워크 인터페이스(L1)의 4개 계층으로 모듈화한 사실상(De facto) 표준 프로토콜 스택.
- **Thin-Waist (모래시계 모델)**: 상위의 다양한 응용/전송 프로토콜과 하위의 다양한 물리망 사이에서 유일한 공통 분모로 IP 계층이 중심을 이루는 아키텍처.

</details>

- 정의/개념: 이기종 네트워크를 상호 연결하기 위해 IP 프로토콜을 중심(Thin-Waist)으로 **응용, 전송, 인터넷, 네트워크 인터페이스 4단계로 구조화한 인터넷 표준 프로토콜 스택**
- 배경/필요성: 초기 독점 통신 벤더 간 비호환성으로 인한 **범세계적 인터넷 망 연동 불가, 복잡한 7계층 오버헤드 및 확장성 한계 해결 불가**

#### 한줄 요약
- IP 중심의 모래시계(Thin-Waist) 구조와 종단 간 원칙(End-to-End)을 통해 글로벌 인터넷을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **End-to-End Principle (종단 간 원칙)**: 네트워크 코어(라우터)는 단순 패킷 전달만 수행하고, 신뢰성 제어와 오류 복구는 종단 호스트(L4 TCP)가 전담한다는 원칙.
- **Best-Effort Delivery (최선 노력 전달)**: IP 계층이 패킷 전달의 성공을 100% 보장하지 않고 최선의 노력으로만 포워딩하는 비연결형 전송 방식.

</details>

- 복잡한 네트워크 제어를 배제하고 종단 호스트가 신뢰성을 제어하는 **종단 간 원칙(End-to-End)**
- IP 프로토콜 하나로 상위 응용과 하위 물리망을 모두 수용하는 **모래시계(Thin-Waist) 아키텍처**
- 신뢰성이 필요한 연결형(TCP)과 초저지연 비연결형(UDP)을 선택하는 **유연한 전송 계층 제공**

#### 한줄 요약
- 종단 간 원칙, Thin-Waist 구조, TCP/UDP 전송 계층 분리를 통해 높은 확장성과 유연성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCP/IP 4계층 PDU 매핑**: Application(Data), Transport(Segment/Datagram), Internet(Packet), Network Interface(Frame).

</details>

```text
[TCP/IP 4계층 프로토콜 스택 및 모래시계 구조]
|-- L4. Application Layer (HTTP, HTTPS, DNS, SSH, gRPC) -> Data/Message
|-- L3. Transport Layer (TCP: 신뢰성/흐름제어, UDP: 저지연 전송) -> Segment
|-- L2. Internet Layer (IPv4, IPv6, ICMP, ARP, OSPF, BGP) -> Packet (Thin-Waist 중심)
`-- L1. Network Access Layer (Ethernet, Wi-Fi, 5G, Optical PHY/MAC) -> Frame / Bit
```

선의 의미: 계층 및 상위 계층 데이터가 하위로 캡슐화되어 IP 계층을 중심으로 이기종 네트워크 망을 경유해 전달되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **L4 응용 계층 (Application)** | 사용자 프로세스 인터페이스, **데이터 포맷 변환 및 세션 관리를 통합 수행** | HTTP, DNS, TLS |
| **L3 전송 계층 (Transport)** | 포트(Port) 기반 **종단 간(End-to-End) 신뢰성 제어(TCP) 및 고속 비연결 전송(UDP)** | TCP, UDP |
| **L2 인터넷 계층 (Internet)** | 논리 IP 주소 기반 **호스트 식별, 패킷 최적 경로 결정(Routing) 및 단편화 제어** | IPv4, IPv6, ICMP |
| **L1 네트워크 인터페이스** | 인접 노드 간 **MAC 프레임 전송, CRC 오류 검출 및 물리 전자기 신호 송수신** | Ethernet, Wi-Fi |

#### 한줄 요약
- 응용(Data), 전송(Segment), 인터넷(Packet), 네트워크 인터페이스(Frame)가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TCP/IP 패킷 포워딩 5단계**: 송신단 응용 데이터 생성 $\to$ L4 TCP 포트 세그먼트화 $\to$ L3 IP 패킷 캡슐화 $\to$ 라우터 넥스트홉 포워딩 $\to$ 수신단 역캡슐화.

</details>

```text
송신 호스트 (캡슐화)                                       수신 호스트 (역캡슐화)
┌──────────────────────────────┐                         ┌──────────────────────────────┐
│ 1. [L4] 응용 페이로드 생성   │                         │ 5. [L4] 웹서버 프로세스 수신│
└──────────────┬───────────────┘                         └──────────────▲───────────────┘
               │                                                        │
               ▼                                                        │
┌──────────────────────────────┐                         ┌──────────────┴───────────────┐
│ 2. [L3] TCP 헤더 부착 (Port) │                         │ 4. [L3] 포트 디멀티플렉싱    │
└──────────────┬───────────────┘                         └──────────────▲───────────────┘
               │                                                        │
               ▼                                                        │
┌──────────────────────────────┐                         ┌──────────────┴───────────────┐
│ 3. [L2] IP 헤더 부착 (Packet)│                         │ 3. [L2] IP 검증 및 목적지 확인│
└──────────────┬───────────────┘                         └──────────────▲───────────────┘
               │                                                        │
               ▼                                                        │
┌──────────────────────────────┐   [L3 라우터 넥스트홉]   ┌──────────────┴───────────────┐
│ 4. [L1] MAC 프레임 송출 (PHY)│ ──▶ [IP 라우팅 포워딩] ──▶ │ 2. [L1] MAC/CRC 오류 검사   │
└──────────────────────────────┘                         └──────────────────────────────┘
```

#### 한줄 요약
- 송신단 캡슐화 → 라우터 L3 포워딩 → 수신단 역캡슐화 파이프라인을 거쳐 데이터가 종단 간 전달된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCP/IP 4계층 vs OSI 7계층**: 실용적 구현 표준(TCP/IP 4계층)과 학술적 이론 참조 모델(OSI 7계층).

</details>

| 비교 항목 | TCP/IP 4계층 모델 | OSI 7계층 참조 모델 |
|:---|:---|:---|
| **모델 성격 및 위상** | **실제 인터넷 구현 기반 사실상 표준 (De facto)** | 통신 시스템 표준 설계를 위한 **참조 모델 (De jure)** |
| **계층 수 및 구조** | **4개 계층 (단순하고 실용적인 통합 구조)** | **7개 계층 (엄격하게 분리된 세분화 구조)** |
| **세션 및 표현 계층** | **응용 계층(L4) 내 소프트웨어 라이브러리로 통합**| 세션(L5), 표현(L6) 독립 계층 분리 |
| **데이터링크 및 물리** | **네트워크 접근 계층(L1)으로 통합** | 데이터링크(L2), 물리(L1) 독립 분리 |
| **신뢰성 제어 책임** | **종단 호스트(L4 TCP)에 집중 위임** | 각 계층별 분산 오류 제어 지향 |

#### 한줄 요약
- TCP/IP는 구현 중심의 실용적 4계층 구조이며, OSI는 개념적 참조를 위한 엄격한 7계층 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MSS Clamping**: 터널링(IPsec/VXLAN) 오버헤드로 인한 MTU 초과 단편화를 막기 위해 TCP SYN 패킷의 MSS 값을 강제로 축소 조정하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| VPN 터널링 오버헤드로 인한 MTU 초과 및 IP 단편화 지연 | **경로 MTU 탐색(PMTUD) 및 라우터 `TCP MSS Clamping` 적용** | 패킷 분할 오버헤드 방지 및 전송 처리량 극대화 |
| 실시간 스트리밍 시 TCP 재전송 지연으로 인한 버퍼링 장애 | **실시간 트래픽에 `UDP 기반 QUIC (HTTP/3) 및 WebRTC` 프로토콜 도입** | 연결 설정 지연 제거 및 Head-of-Line Blocking 해소 |
| 네트워크 전면 장애 발생 시 원인 계층 식별 지연 | **L1(물리링크) $\to$ L2(ARP) $\to$ L3(IP) $\to$ L4(Port) `상향식 계층 진단`** | 문제 식별 시간 단축 및 MTTR 극소화 |
| IP 단편화(Fragmentation)를 악용한 방화벽 우회 해킹 공격 | **보안 게이트웨이에서 `비정상 조각 패킷(Teardrop/Overlap) 드롭` 강제** | 네트워크 계층 침해 공격 원천 차단 |

#### 한줄 요약
- MSS 클램핑, QUIC 프로토콜 전환, 상향식 계층 진단, 단편화 패킷 보안 필터링으로 운영한다.

## Ⅶ. 결론

- 범세계적인 인터넷 통신 인프라를 구축하고 서비스 신뢰성을 보장하기 위해 **TCP/IP 4계층의 Thin-Waist(IP) 아키텍처와 종단 간 원칙(End-to-End)을 기반으로 시스템을 구현**하고, **QUIC/HTTP3 고속화 프로토콜과 상향식 장애 진단 체계**를 결합하여 확장 가능하고 견고한 엔터프라이즈 네트워크 완성

#### 한줄 요약
- TCP/IP 4계층 모델은 IP 중심의 모래시계 아키텍처와 종단 간 원칙을 통해 오늘날 글로벌 인터넷의 표준 프로토콜 스택을 제공하는 핵심 네트워크 모델이다.
