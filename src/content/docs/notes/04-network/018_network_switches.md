## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스위칭 계층(Switching Layer)**: 패킷을 전달하거나 분기할 때 참조하는 OSI 7계층 기준(L2 MAC, L3 IP, L4 Port/세션, L7 Payload)에 따른 장비 분류 체계.
- **L2 스위치**: 데이터링크 계층의 48비트 MAC 주소를 참조하여 동일 VLAN 세그먼트 내에서 프레임을 하드웨어로 고속 포워딩하는 장비.
- **L3 스위치**: 네트워크 계층의 IP 주소와 하드웨어 FIB(Forwarding Information Base)를 참조하여 서브넷 간 고속 인터-VLAN 라우팅을 수행하는 장비.
- **L4 스위치**: 전송 계층의 5-튜플(IP/Port/프로토콜) 정보를 파싱하여 서버 부하 분산(Server Load Balancing, SLB)을 수행하는 장비.
- **L7 스위치**: 애플리케이션 계층의 HTTP URL, 헤더, 쿠키, 페이로드 정보를 분석하여 콘텐츠 기반 라우팅 및 지능형 트래픽 제어를 수행하는 장비.

</details>

- 정의/개념: 인입 패킷의 헤더 및 페이로드 분석 깊이(L2~L7)에 따라 최적의 포워딩, 라우팅, 부하 분산 및 콘텐츠 분기를 수행하는 **계층별 네트워크 스위칭 장비 분류 체계**
- 배경/필요성: 단순 L2/L3 패킷 전달을 넘어 웹 애플리케이션 트래픽 증가에 따른 고가용성 부하 분산(SLB), 세션 유지 및 마이크로서비스 콘텐츠 라우팅 요구

#### 한줄 요약
- 참조 계층(L2 MAC, L3 IP, L4 5-튜플, L7 페이로드)에 따라 포워딩과 부하 분산 책임을 분담한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **5-튜플(5-Tuple)**: 패킷 통신 세션을 식별하는 5가지 요소인 출발지 IP, 목적지 IP, 출발지 포트, 목적지 포트, 전송 프로토콜(TCP/UDP).
- **콘텐츠 기반 라우팅(Content-based Routing)**: L7 계층에서 HTTP Request URI, Host 헤더, Cookie 값 등을 기반으로 백엔드 서비스 풀을 선별 지정하는 라우팅.

</details>

- **L2/L3**: ASIC 칩셋 기반 하드웨어 와이어 스피드(Wire-speed) 패킷 포워딩 및 인터-VLAN 라우팅 제공
- **L4**: **5-튜플** 세션 테이블 관리를 통한 전송 계층 로드 밸런싱(SLB) 및 실시간 헬스 체크 지원
- **L7**: **URL, HTTP 헤더, 쿠키** 분석을 통한 콘텐츠 지능형 분기, SSL/TLS 가속 및 WAF 연계 지원

#### 한줄 요약
- 하위 계층(L2/L3)은 고속 전송을, 상위 계층(L4/L7)은 지능형 세션 및 콘텐츠 분기를 수행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 정보 베이스(FIB)**: L3 스위치에서 라우팅 테이블(RIB)을 하드웨어 ASIC(TCAM)에 컴파일하여 고속 룩업을 지원하는 데이터베이스.

</details>

```text
[ 계층별 스위치 패킷 분석 구조 ]

 [ L7 스위치 ] ──▶ L7 응용 계층 (HTTP URL, 헤더, 쿠키, 페이로드 분석)
       │
 [ L4 스위치 ] ──▶ L4 전송 계층 (TCP/UDP 포트, 5-튜플 세션 상태 관리)
       │
 [ L3 스위치 ] ──▶ L3 네트워크 계층 (IP 주소, FIB/TCAM 하드웨어 라우팅)
       │
 [ L2 스위치 ] ──▶ L2 데이터링크 계층 (MAC 주소, CAM 테이블 기반 스위칭)
```

선의 의미: 상위 계층으로 갈수록 패킷 파싱 깊이와 상태 관리 복잡도가 증가하는 계층적 관계

| 구성요소 | 책임 | 식별 기준 |
|:---|:---|:---|
| **L2 스위치** | CAM 테이블 조회를 통한 동일 브로드캐스트 도메인(VLAN) 내 프레임 포워딩 | 48비트 MAC 주소 |
| **L3 스위치** | TCAM/FIB 기반 고속 인터-VLAN 라우팅 및 서브넷 간 패킷 전달 | 32/128비트 IP 주소 |
| **L4 스위치** | 전송 계층 세션 식별 및 서버 팜 대상 트래픽 부하 분산(SLB) | **5-튜플**, TCP/UDP 포트 |
| **L7 스위치** | 애플리케이션 계층 데이터 파싱 및 정밀 콘텐츠 기반 서비스 분기 | URL, Header, Cookie, Payload |

#### 한줄 요약
- L2/L3는 하드웨어 주소 포워딩을, L4/L7은 세션 및 애플리케이션 페이로드 기반 분기를 담당한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **최소 계층 선택 원칙**: 요구되는 트래픽 제어 목적(단순 전달 vs 부하 분산 vs 콘텐츠 분석)에 부합하는 최하위 계층 장비를 적용하여 처리 지연과 비용을 최적화하는 설계 원칙.

</details>

```text
1. 네트워크 설계 및 트래픽 분기 요구사항 분석
            │
            ├─ [동일 VLAN 내 단순 단말 연결] ──▶ 2a. L2 스위치 선정 (MAC 포워딩)
            ├─ [서브넷 간 고속 라우팅 필요] ──▶ 2b. L3 스위치 선정 (FIB 하드웨어 라우팅)
            ├─ [포트 기반 서버 부하 분산] ─────▶ 2c. L4 스위치 선정 (5-튜플 SLB)
            └─ [URL/쿠키 기반 정밀 분기 필요] ─▶ 2d. L7 스위치 선정 (콘텐츠 라우팅/TLS 종료)
```

**동작 원리**

1. **요구사항 식별**: 단순 물리 접속, 서브넷 간 통신, 서버 로드 밸런싱, 애플리케이션 라우팅 여부 판정
2. **L2 적용**: 단말 접속 및 동일 네트워크 세그먼트 내 와이어 스피드 스위칭 배포
3. **L3 적용**: VLAN 간 트래픽 라우팅 및 기본 게이트웨이(SVI) 역할 수행
4. **L4 적용**: TCP/UDP 포트 기반의 서버 팜 부하 분산 및 실시간 서버 상태 감시 배포
5. **L7 적용**: URL 패턴 매핑, 모바일/PC 분기, TLS 암복호화 및 세션 어피니티(Sticky Session) 적용

#### 한줄 요약
- 트래픽 제어 요구수준에 따라 L2, L3, L4, L7 장비를 선별 배치하여 성능과 기능을 최적화한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLS 종료(TLS Termination)**: L7 로드 밸런서가 클라이언트와의 HTTPS 암호화 세션을 복호화하여 백엔드로 전달하고 인증서 관리를 일원화하는 기능.

</details>

| 비교 항목 | L2 / L3 스위치 | L4 스위치 | L7 스위치 |
|:---|:---|:---|:---|
| **적용 기준** | 단말 접속 및 서브넷 간 **경로 전달** | 서버 팜 대상 **트래픽 부하 분산** | 콘텐츠/URL 기반 **응용 서비스 분기** |
| **분석 데이터** | L2 MAC 주소 / L3 IP 헤더 | **5-튜플**, TCP 시퀀스/SYN 상태 | HTTP Method, URL, Cookie, Body |
| **상태 관리(State)** | 비상태형 (Stateless) | **세션 테이블 유지 (Stateful)** | 애플리케이션 세션 및 트랜잭션 관리 |
| **처리 성능 및 지연** | 와이어 스피드 (초저지연, 하드웨어) | 고성능 (마이크로초 단위) | 페이로드 버퍼링/복호화로 상대적 지연 증가 |

#### 한줄 요약
- L2/L3는 비상태형 초고속 전송을, L4는 전송 세션 부하 분산을, L7은 응용 계층 정밀 제어를 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상태 확인(Health Check)**: L4/L7 스위치가 백엔드 서버의 가용성을 지속 확인하여 장애 서버로의 트래픽 유입을 차단하는 메커니즘.
- **세션 동기화(Session Synchronization)**: L4/L7 이중화 구성 시 Active-Standby 장비 간 세션 테이블을 실시간 복제하여 절체 시 통신 단절을 방지하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 백엔드 애플리케이션 다운 시 트래픽이 계속 유입되어 서비스 오류 발생 | L4/L7 **L3/L4/L7 다계층 상태 확인(Health Check)** 활성화 | 장애 인스턴스 자동 격리 및 정상 서버로의 즉시 우회 |
| L4 로드 밸런서 장애 절체(Failover) 시 클라이언트 연결 세션 단절 | Active-Standby 간 **세션 상태 실시간 동기화(Session Sync)** 적용 | 무중단 세션 인계 및 사용자 재로그인 방지 |
| HTTPS 암호화로 인해 L7 콘텐츠 기반 라우팅 및 보안 검사 불가 | L7 스위치에서 **SSL/TLS 종료(Offloading/Termination)** 구성 | 암호화 트래픽 복호화 후 URL/쿠키 분석 및 백엔드 CPU 부하 경감 |

#### 한줄 요약
- 다계층 헬스 체크, 세션 상태 동기화, TLS 오프로딩 구성을 통해 로드 밸런싱의 가용성을 보장한다.

## Ⅶ. 결론

- 엔터프라이즈 인프라 설계 시 전달 속도와 분석 깊이의 상충관계를 고려하여, 백본 및 집선 구간에는 **L2/L3 하드웨어 스위치**를 배치하고 애플리케이션 프런트엔드에는 **L4/L7 로드 밸런서**를 배치하는 계층적 분계점 설계를 확립

#### 한줄 요약
- 트래픽 처리 요구수준에 부합하는 계층별 스위치를 적재적소에 배치하여 고가용성 망을 구축한다.
