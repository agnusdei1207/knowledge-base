## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Network Switches (네트워크 스위치)**: 참조하는 OSI 계층(L2 MAC, L3 IP, L4 Port, L7 Payload)에 따라 패킷을 스위칭, 라우팅, 부하 분산하는 네트워크 장비.
- **5-Tuple (5-튜플)**: 출발지 IP, 목적지 IP, 출발지 포트, 목적지 포트, 프로토콜(TCP/UDP)로 구성된 L4 통신 세션 식별자.

</details>

- 정의/개념: 인입 패킷의 분석 계층 깊이에 따라 **L2 프레임 포워딩, L3 서브넷 라우팅, L4 서버 부하 분산 및 L7 콘텐츠 라우팅을 수행하는 스위치 장비군**
- 배경/필요성: 단순한 L2 MAC 주소 및 L3 IP 주소 기반의 패킷 전달 장비만으로는 서버 팜(Farm) 대상 트래픽 분산, 세션 지속성 유지, HTTP URL/헤더 기반의 지능형 마이크로서비스 라우팅 및 SSL/TLS 암복호화 처리를 스위칭 경로 상에서 직접 수행할 수 없는 한계를 극복하기 위해, 패킷을 들여다보는 분석 깊이에 따라 L2(MAC 스위칭), L3(IP 라우팅), L4(5-튜플 SLB 부하 분산), L7(애플리케이션 콘텐츠 라우팅)으로 역할을 전문화한 다계층 스위치 장비군을 도입하여 **엔드투엔드 트래픽 처리 성능의 극대화와 애플리케이션 가용성/보안성의 계층적 최적화**를 달성할 필요

#### 한줄 요약
- L2 MAC, L3 IP, L4 포트, L7 콘텐츠 페이로드를 계층별로 분석하여 트래픽을 최적 분기한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Content-Based Routing**: L7 계층에서 HTTP Request URL, Host 헤더, Cookie 값 등을 파싱하여 특정 백엔드 서비스 풀로 트래픽을 라우팅하는 기술.
- **Wire-Speed Forwarding**: 스위치 포트의 물리적 최대 대역폭 속도로 패킷 손실이나 지연 없이 하드웨어 ASIC에서 실시간 전달하는 성능.

</details>

- **L2/L3**: ASIC 하드웨어 기반 와이어 스피드(Wire-speed) 프레임 포워딩 및 인터-VLAN 고속 라우팅
- **L4**: **5-튜플 세션 테이블** 기반의 전송 계층 서버 부하 분산(SLB) 및 L4 헬스 체크
- **L7**: **URL, HTTP 헤더, 쿠키** 분석을 통한 콘텐츠 기반 라우팅 및 SSL/TLS 가속 오프로딩

#### 한줄 요약
- L2/L3는 하드웨어 초고속 전송을, L4/L7은 지능형 세션 관리 및 응용 콘텐츠 분기를 수행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCAM (Ternary CAM)**: L3 스위치에서 0, 1, Don't Care(X) 비트 마스크를 지원하여 라우팅 테이블(FIB)을 1클록 만에 검색하는 초고속 연관 메모리.

</details>

```text
[L2~L7 스위칭 계층 및 패킷 분석 깊이 아키텍처]
|-- L7 Application Switch (HTTP URL, Host Header, Cookie, Payload 파싱 -> 콘텐츠 라우팅)
|-- L4 Transport Switch (TCP/UDP Port, 5-Tuple Session Table -> 서버 부하 분산 SLB)
|-- L3 Network Switch (IP Address, TCAM / FIB Routing -> Inter-VLAN 하드웨어 라우팅)
`-- L2 Data Link Switch (48-bit MAC Address, CAM Table -> 동일 VLAN 프레임 스위칭)
```

선의 의미: 계층 및 하위 L2에서 상위 L7으로 올라갈수록 패킷 파싱 깊이와 상태 관리 복잡도가 증가하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 식별 기준 |
|:---|:---|:---|
| **L2 스위치** | CAM 테이블 조회를 통한 **동일 브로드캐스트 도메인(VLAN) 내 프레임 하드웨어 포워딩** | 48비트 MAC 주소 |
| **L3 스위치** | TCAM/FIB 하드웨어 기반 **서브넷 간 고속 인터-VLAN 라우팅 및 패킷 전달** | 32/128비트 IP 주소 |
| **L4 스위치** | 전송 계층 세션 식별 및 **백엔드 서버 팜 대상 트래픽 부하 분산(SLB)과 헬스 체크** | **5-튜플**, TCP/UDP 포트 |
| **L7 스위치** | 애플리케이션 계층 데이터 파싱 및 **정밀 콘텐츠 기반 서비스 분기, TLS 오프로딩** | URL, Header, Cookie |

#### 한줄 요약
- 같은 전달 경로 위의 장비가 들여다보는 깊이를 한 계층 더할 때마다 상위 계층이 하던 판단을 대신 떠맡지만, 그만큼 세션 상태를 유지할 책임도 함께 넘겨받는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **계층 선택 4단계**: 패킷 인입 $\to$ 요구 기능 식별 $\to$ 해당 계층 분석(L2~L7) $\to$ 타깃 포트/서버로 전송.

</details>

```text
인입 패킷의 계층별 처리 및 스위칭 흐름
        │
   1. [패킷 인입 및 요구 식별] 스위칭/라우팅/부하분산/콘텐츠분기 요구 판정
        │
   ┌────┼───────────────────────────┬───────────────────────────┐
   │    │                           │                           │
  [L2] [L3]                        [L4]                        [L7]
   │    │                           │                           │
2A. MAC 2B. IP                      2C. 5-Tuple 세션           2D. HTTP URL/쿠키
   조회     조회 (TCAM)                 해시 분배 (SLB)             파싱 및 TLS 복호화
   │    │                           │                           │
   └────┴───────────────────────────┴───────────────────────────┘
        ▼
   3. [최종 타깃 포트 / 백엔드 서버로 고속 전달 완료]
```

#### 한줄 요약
- L2·L3 갈래는 주소 조회 한 번으로 끝나 상태를 남기지 않는 반면, L4·L7 갈래는 세션 테이블과 복호화 부담을 떠안아 전달 속도를 판단 정밀도와 맞바꾼다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Stateless vs Stateful**: 세션 상태를 저장하지 않는 단순 전달(L2/L3)과 세션 연결 테이블을 메모리에 유지하는 제어(L4/L7).

</details>

| 비교 항목 | L2 / L3 스위치 | L4 스위치 | L7 스위치 |
|:---|:---|:---|:---|
| **핵심 엔지니어링 목적**| **단말 접속 및 서브넷 간 경로 전달** | **서버 팜 대상 전송 부하 분산(SLB)** | **콘텐츠/URL 기반 응용 서비스 분기** |
| **패킷 분석 대상 데이터**| **L2 MAC 주소 / L3 IP 헤더** | **5-튜플, TCP SYN/ACK 플래그** | **HTTP Method, URL, Cookie, Body** |
| **세션 상태 관리(State)**| **비상태형 (Stateless)** | **세션 테이블 유지 (Stateful)** | **애플리케이션 세션 및 트랜잭션 관리**|
| **처리 성능 및 지연** | 와이어 스피드 (초저지연, ASIC) | 초고성능 (마이크로초 단위) | 페이로드 버퍼링/복호화로 상대적 지연 |

#### 한줄 요약
- L2/L3는 비상태형 초저지연 전송을, L4는 5-튜플 부하 분산을, L7은 응용 계층 정밀 제어를 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Health Check (상태 확인)**: L4/L7 로드 밸런서가 백엔드 서버의 포트(TCP) 및 응용 응답(HTTP 200 OK)을 주기적으로 감시하여 장애 서버를 격리하는 기능.
- **Session Synchronization**: 이중화된 로드 밸런서 간에 세션 테이블을 실시간 동기화하여 Failover 발생 시 세션 끊김을 방지하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 백엔드 WAS 애플리케이션 다운 시 트래픽 유입으로 장애 전파 | **L4/L7 `다계층 헬스 체크(TCP 포트 + HTTP 200 OK)` 구성** | 장애 인스턴스 자동 격리 및 정상 서버 우회 |
| L4 로드 밸런서 페일오버 발생 시 클라이언트 연결 세션 단절 | **Active-Standby 간 `세션 상태 실시간 동기화(Session Sync)`** | 무순단 세션 인계 및 재로그인 방지 |
| HTTPS 암호화로 인해 L7 콘텐츠 기반 라우팅 및 보안 검사 불가 | **L7 스위치에 `SSL/TLS 가속 오프로딩(TLS Termination)` 도입** | 암호화 트래픽 복호화 및 백엔드 CPU 절감 |
| L7 스위치의 과도한 정규식 파싱으로 인한 스위치 CPU 과부하 | **URL 라우팅 규칙 단순화 및 L4와 L7 `계층 분리 2단계 로드 밸런싱`** | 처리 성능 및 확장성 극대화 |

#### 한줄 요약
- 다계층 헬스 체크, 세션 상태 동기화, TLS 오프로딩, 계층 분리 설계로 운영한다.

## Ⅶ. 결론

- 전통적인 온프레미스 데이터센터 하드웨어 어플라이언스부터 클라우드 가상 로드 밸런서(AWS NLB/ALB) 및 쿠버네티스 Ingress Controller/Envoy 프록시에 이르기까지 **모든 네트워크 트래픽 전달과 애플리케이션 딜리버리를 관장하는 핵심 인프라 스택**으로 확립되었으며, 실무 아키텍처 설계 시에는 **L2/L3 계층의 ASIC 하드웨어 와이어 스피드 포워딩, L4 계층의 DSR(Direct Server Return) 기반 대용량 트래픽 바이패스, L7 계층의 TLS Termination 및 마이크로서비스 URL 라우팅, 액티브-스탠바이 간 세션 동기화(Session Sync)**를 계층별로 결합하여 최적의 확장성과 성능을 완성

#### 한줄 요약
- L2~L7 스위칭 계층은 패킷 분석 깊이에 따라 포워딩, 라우팅, 부하 분산, 콘텐츠 제어를 분담하여 고성능·고가용성 망을 지탱하는 핵심 네트워크 장비군이다.
