## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **맨체스터 인코딩 (Manchester Encoding)**: 데이터 비트를 보낼 때, 비트 중간에 무조건 전압을 위아래로 한 번 꺾어줘서 "나 지금 데이터 쏘고 있다!" 하고 생존 신고(클럭 동기화)를 하는 구식 랜선 통신법이다.
- **NRZ (비복귀 영점)**: 1은 플러스 전압, 0은 마이너스 전압으로 쿨하게 쏘는 방식인데, 1이 백 번 연속으로 나오면 전압이 가만히 있어서 수신자가 랜선 끊긴 줄 알고 잠들어버리는(동기화 붕괴) 멍청한 결함이 있다.

</details>

- 정의: **맨체스터 인코딩**은 비트 전송 중간 시점에 무조건 전압을 반전시켜서, 별도의 클럭선 없이도 수신자가 알아서 박자(동기화)를 맞추게 만드는 자가 동기화(Self-Clocking) 회선 부호화 기술이다.
- 배경: 기존 **NRZ** 방식으로 랜선을 깔았더니 0이나 1이 연속으로 나올 때 박자를 놓치고 에러가 터져서, **강제로 중간에 한 번씩 전압을 꺾어주는 맨체스터 방식을 초기 이더넷(10BASE-T) 기본 표준으로 박아버렸다.**

#### 한줄 요약

- 수신자가 박자를 놓치지 않게, 비트 중간마다 강제로 전압 파형을 한 번씩 꺾어주는 동기화 떡칠 부호화 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **PLL (위상 고정 루프)**: 수신자가 꺾이는 전압 파형(에지)을 보고 "아, 이 타이밍이구나!" 하고 자기 심장 박동(클럭)을 송신자랑 똑같이 맞추는 정밀 동기화 회로다.
- **보드율 (Baud Rate)**: 1초에 전압 파형이 몇 번이나 꺾이는지(신호 변화율)를 나타낸다. 맨체스터는 비트 하나 보낼 때 전압을 두 번씩 꺾어대니까 보드율이 쓸데없이 두 배나 높다(가성비 폭망).

</details>

- **무조건 반전 (자가 동기화 짱짱맨)**: 데이터가 0이든 1이든 비트 중간에 무조건 전압이 한 번 꺾여서, 수신 측 **PLL** 회로가 알아서 박자(클럭)를 찰떡같이 복구해 낸다.
- **직류 성분(DC Wander) 컷트**: 플러스랑 마이너스 전압을 정확히 반반씩 써서, 랜선에 전기가 고여서 생기는 직류 노이즈를 원천 차단한다.
- **주파수 가성비 폭망 (대역폭 낭비)**: 비트 1개 쏠 때 전압을 2번씩 바꾸느라 오버를 떨어서, 일반 방식(NRZ)보다 주파수 대역폭을 무려 두 배나 더 처먹는다.

#### 한줄 요약

- 동기화 하나는 기가 막히게 잘 잡고 직류 노이즈도 컷트하지만, 그 대가로 주파수 대역폭을 두 배나 낭비하는 극단적인 놈이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **에지 검출 (Edge Detection)**: 전압이 플러스에서 마이너스로 꼬라박는지(하강 에지), 마이너스에서 플러스로 치솟는지(상승 에지) 귀신같이 낚아채는 센서다.
- **지터 (Jitter)**: 전압이 꺾이는 타이밍이 칼같이 떨어져야 하는데, 케이블이 길고 노이즈가 껴서 타이밍이 수전증 걸린 것처럼 미세하게 덜덜 떨리는 빡치는 현상이다.

</details>

```text
[ 맨체스터 전압 꺾기 팩트 폭행 구조 ]

[ 1. 맨체스터 인코더 ] ── (원본 데이터에 심장 박동(클럭) 섞어서 전압 꺾음)
      │
      ▼ (구리 랜선 타고 찌그러지며 날아감)
[ 2. 에지 검출기 ] ── (수신 측: 어? 전압 떨어졌다! 에지 포착 완료)
      │
      ▼
[ 3. PLL 클럭 복구기 ] ── (에지 타이밍 맞춰서 수신 측 심장 박동 살려냄)
      │
      ▼
[ 4. 데이터 판정기 ] ── (전압 내려갔으면 0, 올라갔으면 1. 원본 비트 해독함)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **맨체스터 인코더** | 비트 중간에 무조건 **전압 한 번 꺾어서 파형 쏴주는 놈** | Encoder |
| **에지 검출기** | 수신 파형에서 전압이 오르는지 내리는지 **칼타이밍 낚아채는 센서** | Edge Detector |
| **PLL 복구기** | 에지 타이밍 보고 **수신 측 심장 박동(클럭)을 송신자랑 똑같이 맞추는 칩** | PLL |
| **데이터 판정기** | 전압 내려가면 0, 올라가면 1로 **원본 데이터가 뭔지 최종 판정하는 판사** | Decoder |

#### 한줄 요약

- 꺾어서 쏘고(인코더) $\to$ 언제 꺾이는지 낚아채고(에지 검출) $\to$ 박자 맞춘 뒤(PLL) $\to$ 데이터로 해독(판정)하는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **중앙 천이 (Mid-bit Transition)**: 무조건 비트 한가운데서 전압을 위아래로 한 번 꺾어주는 맨체스터의 정체성이자 핵심 동작이다.

</details>

```text
[ 자가 동기화 전압 꺾기 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [중앙 천이 파형 전송]     │
│ (송신: 비트 중간에 강제로 전압 꺾어서 쏨. 하강=0, 상승=1)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [수신 파형 전달]          │
│ (구리 랜선 통과: 노이즈 먹고 살짝 찌그러진 전압 도착)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [천이 시점(에지) 낚아채기]│
│ (수신: 어 전압 꺾였다! 타이밍 포착 완료)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [수신 클럭 복구 (PLL)]    │
│ (수신: 낚아챈 타이밍에 맞춰서 멈췄던 수신 측 클럭 다시 살림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [비트 판정 및 복원]       │
│ (수신: 전압 방향 보고 원본 0/1 비트로 해독 완료)
└──────────────────────────────┘
```

### 동작 원리

1. 전압 꺾어서 쏘기: 송신 측에서 데이터 비트와 클럭 신호를 섞어, 비트 한가운데서 전압이 무조건 바뀌는 파형을 쏜다.
2. 수신 파형 도착: 물리 랜선을 통과하며 잡음과 지터(수전증)가 일부 낀 파형을 수신기가 받는다.
3. 에지 감지: 수신 에지 검출기가 파형이 치솟거나 꼬라박는 타이밍(에지)을 정밀하게 잡아낸다.
4. 박자(클럭) 맞추기: 잡아낸 타이밍을 PLL 회로에 넣어서 송신자랑 똑같은 박자로 클럭을 복구한다.
5. 데이터 해독: 전압이 떨어졌는지(0) 올라갔는지(1) 판정해서 원래 데이터를 쫙 뽑아낸다.

#### 한줄 요약

- 전압 꺾어서 보내면 $\to$ 에지 타이밍 잡고 $\to$ 그 박자에 맞춰서 클럭 살리고 비트를 해독하는 생존형 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **차분 맨체스터 (Differential Manchester)**: 랜선 극성을 반대로 꽂으면 0과 1이 다 뒤집히는 기본 맨체스터의 멍청함을 고쳐서, 비트 시작 부분에 전압이 꺾이면 0, 안 꺾이면 1로 판정하는 업그레이드 버전이다.

</details>

| 비교 항목 | **표준 맨체스터 (기본형)** | **차분 맨체스터 (업글형)** | **NRZ (효율충)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | 동기화는 쩌는데 **선 거꾸로 꽂으면 바보 됨** | 거꾸로 꽂아도 찰떡같이 알아먹는 **똑똑한 놈** | 대역폭 가성비는 좋은데 **박자 놓치면 바로 뻗음** |
| 비트 판정 기준 | 비트 중간에서 전압이 **올라가냐 내려가냐** | 비트 시작할 때 전압이 **꺾이냐 안 꺾이냐** | 전압 자체가 **플러스냐 마이너스냐** |
| 선 잘못 꽂았을 때 | 0이랑 1 완전히 뒤집어져서 **데이터 싹 다 깨짐** | 방향 안 보고 꺾임만 봐서 **데이터 멀쩡함** | 0이랑 1 완전히 뒤집어져서 **데이터 깨짐** |
| 대역폭 요구량 | 효율 폭망 (NRZ의 두 배) | 효율 폭망 (NRZ의 두 배) | **가성비 굿 (대역폭 아낌)** |
| 주력 활용 분야 | 구형 **10BASE-T 이더넷** 기본 인코딩 | **토큰링** 등 극성 헷갈리는 산업용 폐쇄망 | 기가비트 이더넷, 광통신, RS-232C 등 **고속망** |

#### 한줄 요약

- 맨체스터는 선 거꾸로 꽂으면 바보 되니까 차분을 쓰고, 요즘같이 빠른 기가 인터넷 시대엔 효율 폭망이라 안 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **극성 반전 (Polarity Reversal)**: 초보자가 UTP 랜선을 찝을 때 플러스선이랑 마이너스선을 반대로 꽂아버려서, 표준 맨체스터가 0을 1로, 1을 0으로 멍청하게 거꾸로 읽어버리는 대참사 현상이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 랜선 꽂았더니 **0과 1이 싹 다 뒤집혀서 통신 터짐** | UTP 케이블 선 찝을 때 플러스(+)랑 마이너스(-) 극성을 멍청하게 반대로 찝어버림 (극성 반전) | 거꾸로 꽂아도 알아먹는 **차분 맨체스터** 쓰거나, 수신 칩셋에 Auto-Correction 기능 켬 | 랜선 뻘짓으로 통신 전체가 먹통 되는 개그 막아줌 |
| 기가비트(Gbps) 속도 올리려니까 **대역폭 부족해서 랜카드 뻗음** | 맨체스터는 비트 하나 쏠 때마다 전압 두 번씩 꺾느라 뻘짓해서 주파수를 두 배나 처먹음 | 기가비트망에선 맨체스터 갖다 버리고 **8B10B, PAM4 같은 초고속 인코딩 기법으로 싹 갈아탐** | 주파수 대역폭 낭비 컷트하고 10Gbps 이상 속도 뚫어버림 |
| 선 길어지니까 타이밍 엇나가서 **클럭 동기화 박살 남** | 케이블이 너무 길면 전압 꺾이는 타이밍(에지)이 수전증 온 것처럼 덜덜 떨림 (지터 누적) | 튼튼한 **수신 PLL 칩** 박고, 중간에 노이즈 잡아주는 **리피터(Repeater)** 설치함 | 타이밍 덜덜 떨리는 거 잡고 통신 에러율(BER) 팍 낮춤 |

#### 한줄 요약

- 선 거꾸로 찝을 거 대비해서 칩셋 보정 켜고, 1Gbps 넘어가면 효율 구린 맨체스터 버리고 8B10B로 갈아타라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 수신 측의 타이밍 동기화 붕괴를 막기 위해, 비트 중앙에서 무조건 전압을 꺾어 클럭과 데이터를 동시에 전송하는 자가 동기화(Self-Clocking) 회선 부호 기조 확립함

#### 한줄 요약

- 맨체스터 인코딩은 초창기 10Mbps 랜선 통신 시절, 박자를 안 놓치기 위해 덩치를 두 배로 부풀려 쐈던 클래식 부호화 기술이다.
