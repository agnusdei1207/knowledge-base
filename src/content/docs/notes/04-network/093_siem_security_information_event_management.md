## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM (보안 정보 및 이벤트 관리)**: 회사 내 모든 방화벽, 서버, PC에서 나오는 수억 개의 로그(기록)를 한곳에 끌어모아서, 빅데이터 분석으로 해커의 흔적을 찾아내는 거대한 보안 관제(CCTV) 센터다.
- **로그 (Log)**: 누가, 언제, 어디서, 무슨 짓을 했는지 서버나 장비가 남겨놓는 발자국 데이터다.

</details>

- 정의: **SIEM** 이종 보안 장비 및 시스템의 파편화된 로그를 통합 수집, 정규화, 상관분석하여 은밀한 보안 위협을 실시간 탐지/관리하는 융합 관제 체계다.
- 배경: 해커가 방화벽 뚫고 $\to$ 서버 접속하고 $\to$ DB 털어가는 다단계(APT) 공격을 치는데, **장비마다 로그가 따로 놀면 전체 공격 흐름(스토리)을 파악할 수 없어서 기반 관제가 불가능했다.**

#### 한줄 요약

- 파편화된 수억 개의 로그 조각을 모아서, 해커가 어떻게 들어와서 뭘 훔쳐 갔는지 하나의 시나리오로 퍼즐을 맞춰주는 빅데이터 뇌다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로그 정규화 (Normalization)**: 방화벽은 'Source IP', 윈도우는 'Client IP'라고 지멋대로 부르는 로그 포맷을 'Src_IP'라는 하나의 공통 언어로 통일시키는 세탁 작업이다.
- **맥락 보강 (Context Enrichment)**: "1.1.1.1이 접속함"이라는 단순 로그에 "이 IP는 북한 해커 IP고, 타겟은 우리 재무팀 DB다"라는 살(맥락)을 붙여주는 작업이다.
- **상관분석 (Correlation)**: "새벽 2시에 VPN 접속 $\to$ 1분 뒤 DB 1만 건 조회 $\to$ USB 복사" 같이 개별 로그를 이어 붙여서 하나의 공격 시나리오(팩트)를 찾아내는 SIEM의 꽃이다.

</details>

- **세탁 (로그 정규화)**: 회사 내 수백 가지 이종 장비의 제각각인 로그 포맷을 표준 공통 필드로 변환한다.
- **조립 (상관분석)**: 다단계 공격의 시간창(Time Window), 사용자, 자산 연관관계를 도출해 점조직 같은 해커의 동선을 하나의 범죄 시나리오로 재구성한다.

#### 한줄 요약

- 지멋대로 생긴 로그를 통일하고, 부가 정보를 살붙임 한 뒤, 퍼즐을 맞춰서 해커의 전체 동선을 잡아낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상관분석 엔진**: 룰(Rule)에 따라 쏟아지는 수백만 개의 로그를 엮어서 "이거 해킹 맞다"고 경보(Alert)를 띄워주는 SIEM의 심장(뇌)이다.

</details>

```text
[ SIEM 빅데이터 수집 및 직관적 비교 구조 ]

[ 1. 방화벽 / 서버 / PC (로그 발생원) ] ── (수만 대 장비에서 1초에 수천 개씩 로그 쏟아냄)
      │
      ▼
[ 2. 수집기 / 품질 검사기 ] ── (로그 긁어옴. 시간 안 맞는 거 쳐냄)
      │
      ▼
[ 3. 정규화 및 맥락 보강기 ] ── (제각각인 포맷 통일하고, 위협 정보(TI) 살 붙임)
      │
  ┌───┴───┐
  │       │
[저장소] [4. 상관분석 엔진] ── (퍼즐 맞추기 시작. 해킹 시나리오 체크 완료!)
          │
          ▼
[ 5. 경보 및 조사 작업대 ] ── (관제 요원 모니터에 빨간불 띄워주고 근거 들이밈)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **수집기 (Collector)** | 사내 모든 장비에서 **로그 긁어오고 시간 오차 맞추는 노가다꾼** | Data Collection |
| **정규화기 (Normalizer)** | 지멋대로 생긴 로그 필드를 **표준 규격으로 예쁘게 포맷팅해 주는 세탁기** | Parsing |
| **상관분석 엔진** | 로그 엮어서 **이게 찐 해킹인지 단일 룰로 직관적 비교하는 뇌** | Correlation Engine |
| **보안 자료 저장소** | 원본 로그랑 세탁된 로그를 **빅데이터로 평생 안전하게 보관하는 창고 (법적 감사용)** | Repository |
| **조사 작업대 (대시보드)** | 관제 요원한테 **"이래서 해킹이다"라고 타임라인 증거 들이미는 모니터** | Dashboard |

#### 한줄 요약

- 로그 긁어오기 $\to$ 포맷 세탁하기 $\to$ 퍼즐 맞추기 $\to$ 요원 모니터에 사이렌 울려주기의 흐름이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **탐지 규칙 (Detection Rule)**: "동일 IP에서 1분 안에 로그인 5번 실패하고 6번째 성공하면 무차별 대입 공격이다"라고 정의해 놓은 공식이다.
- **위험 점수 (Risk Score)**: 쩌리 알람 수천 개 뜨면 요원들이 피로에 뻗으니까, 자산 중요도랑 공격 성공 확률을 계산해서 점수(1~100점) 빡 매겨주는 기능이다.

</details>

```text
[ SIEM 상관분석 및 경보 발생 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [원본 로그 전달 및 품질 검사]
│ (수집기: 방화벽, DB, 스위치 로그 다 긁어옴)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [정규화 및 맥락 보강 이벤트 전달]
│ (정규화기: 필드 이름 'Src_IP'로 통일하고, 블랙리스트 IP 정보 딱 붙임)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [상관분석 및 근거 경보 전달]
│ (엔진: 탐지 룰 걸렸다! 위험 점수 90점. 관제 화면에 빨간불 켜라!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [조사 판정 기록 및 오탐 분석]
│ (관제요원: 로그 까보니까 찐 공격 맞네. 방화벽 차단해!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [개선 탐지 규칙 (Rule) 피드백]
│ (방금 건 오탐이었네? 임계치 수정해서 룰 깎고 다시 1단계로 반복)
└──────────────────────────────┘
```

### 동작 원리

1. 로그 수집 및 검사: 이종 원천(보안장비/네트워크/서버)의 접속/행위 기록을 싹 긁어오고 검사함.
2. 정규화 및 보강: 공통 스키마로 필드를 통일하고 자산/신원 맥락을 결합해 분석 준비 완료.
3. 근거 경보 발령: 상관분석 엔진이 룰을 돌려서 걸리면, 위험 점수를 매겨 경보를 발행함.
4. 조사 판정: 관제 요원이 원본 근거를 보고 찐 해킹인지 오탐인지 체크 후 판정 내림.
5. 룰 튜닝 피드백: 조사 결과를 바탕으로 오탐 안 나게 규칙(Rule)이나 임계치를 계속 깎음(Tuning).

#### 한줄 요약

- 로그 수집 $\to$ 세탁 및 조립 $\to$ 알람 울림 $\to$ 요원이 체크 $\to$ 오탐 줄이는 룰 업데이트의 무한 반복이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **규칙 기반 (Rule-based)**: 과거 경험을 바탕으로 짠 정확한 시나리오 공식이다.
- **행위 기반 (Behavior-based / ML)**: 과거 로그를 AI로 학습해서 평소 패턴을 만든 뒤, 조금만 튀어도 잡아내는 똑똑한 방식이다.
- **위협 정보 (TI, Threat Intel)**: 경찰청 수배자 명단처럼, 사이버 보안 기관에서 받아오는 최신 해커 IP, 도메인 블랙리스트다.

</details>

| SIEM 분석 방식 비교 | **규칙 기반 분석 (Rule)** | **행위 기반 분석 (Behavior / ML)** | **위협 정보 대조 (TI 매칭)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | **"비밀번호 5번 틀리면 도둑이다" (정해진 룰)** | **"얘 평소에 야근 안 하는데 새벽에 왔네?" (눈치/AI)** | **"경찰청 수배자 명단에 있는 얼굴이네" (블랙리스트)** |
| 탐지 원리 | 사람이 미리 짜놓은 시나리오/임계치 조건식 매칭 | 과거 데이터를 머신러닝 돌려서, 평소 패턴(Baseline)에서 벗어나면 탐지 | 외부 기관에서 사 온 최신 악성 IP, 해시값 리스트랑 실시간 대조 |
| 최고 장점 | 확실한 공격 패턴을 **오탐 없이 직관적으로 잡아냄** | 룰로 못 잡는 **신종(제로데이) 공격이나 교묘한 내부자 유출 탐지 가능** | 복잡한 분석 없이 **확실한 외부 공격자(수배자) 원천 컷트 가능** |
| 치명적 한계 | 사람이 일일이 룰 짜야 하고, **변종 공격엔 속수무책임** | 정상 패턴이 튀면(월말 결산 야근 등) **다 해킹으로 잡아서 오탐 파티 열림** | 수배자 명단 업데이트가 느리면 **최신 공격 못 막음** |

#### 한줄 요약

- 뻔한 건 룰로 잡고, 신종 공격은 AI 눈치로 잡고, 수배자는 블랙리스트(TI)로 대조해서 잡아야 완벽하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오탐/미탐 (False Positive/Negative)**: 정상적인 업무를 해킹으로 오해해서 사이렌 울리는 게 오탐, 진짜 해킹인데 못 잡고 놓치는 게 미탐이다.
- **시간 동기화 (NTP)**: 방화벽은 현재 1시인데, DB 서버는 1시 5분으로 시간이 안 맞으면 SIEM이 "해커가 DB 먼저 털고 5분 전 방화벽을 뚫었다?" 같은 타임머신 오판을 해버리므로 무조건 시간(NTP)을 맞춰야 한다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 해커 공격 순서가 뒤죽박죽으로 **타임라인이 꼬임** | 로그 쏴주는 장비들끼리 서버 시간(NTP) 동기화가 안 맞아서 팩트가 틀어짐 | 사내 전 장비에 **NTP 시간 동기화 빡세게 걸고 '로그 품질 검사' 돌림** | 초 단위 상관분석 및 해킹 사건(Incident) 타임라인 정확도 100% 확보 |
| 룰(Rule) 돌렸는데 **로그 필드 누락으로 탐지 안 됨 (미탐)** | 장비마다 내뱉는 로그 수준이 달라서, 필수 분석 필드(예: User ID)가 비어 있음 | **사용 사례(Use Case)** 중심 필수 필드 정의하고 벤더사에 로그 포맷 패치 강제 요구 | 빵꾸난 데이터 채워서 탐지 모듈 완전성 및 무결성 확보 |
| 하루에 알람 10만 개 떠서 **관제 요원들 다 퇴사함 (피로도)** | 쓸데없는 자잘한 스캔 공격까지 다 경보(Alert)를 띄워서 진짜 위험한 걸 놓치게 됨 | 자산 중요도 곱해서 **위험 점수(Risk Score) 높은 것만 띄우고 오탐 룰 계속 깎음(Tuning)** | 관제 피로도(Alert Fatigue) 극복 및 크리티컬 위협 대응 시간(MTTR) 획기적 단축 |

#### 한줄 요약

- 장비 시간 똑바로 맞추고, 비어있는 로그 채워 넣고, 쓰레기 알람 안 뜨게 룰 계속 깎는 게 관제의 핵심이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **사건 시간선 (Incident Timeline)**: 해커가 어떻게 침투해서 어디를 털었는지, 분산된 로그를 시간순으로 쫙 연결해서 하나의 범죄 드라마로 복원한 증거물이다.

</details>

- 파편화된 보안 로그의 분석 한계를 극복하기 위해, **이종 로그 정규화** 및 **규칙/행위/TI 융합 상관분석**, **사건 시간선(Timeline) 복원** 결합한 통합 관제 기조 확립함

#### 한줄 요약

- SIEM은 장비 사서 켜놓는다고 해커를 잡아주는 마법상자가 아니다. 끊임없이 룰을 깎고 오탐을 줄여나가는 관제 요원의 직관적 비교 무기일 뿐이다.
