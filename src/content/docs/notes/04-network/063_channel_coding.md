## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **채널 코딩 (Channel Coding)**: 무선 통신 중에 전파가 찌그러져서 데이터가 깨질까 봐, 원본 데이터에 미리 힌트(패리티 비트)를 잔뜩 끼워 넣어서 보내는 맷집 강화 기술이다.
- **순방향 오류 정정 (FEC, Forward Error Correction)**: 데이터 깨졌다고 "야 다시 보내줘!"(ARQ) 하고 징징대지 않고, 수신자가 알아서 힌트(패리티) 보고 깨진 데이터를 스스로 고쳐버리는 상남자식 오류 복구법이다.

</details>

- 정의: **채널 코딩** 전파를 쏘기 전에 원본 데이터에 여분의 힌트(패리티) 비트를 덕지덕지 붙여서, 수신 측에서 **순방향 오류 정정(FEC)** 을 통해 깨진 비트를 스스로 찾아내고 복원하는 무선 신호 처리 기술이다.
- 배경: 5G, LTE 같은 고속 무선 통신에서는 전파가 수시로 깨지는데, 그때마다 "다시 보내줘" 하면 핑(지연 시간)이 터지니까, **안 묻고 안 따지고 수신자가 직접 고치게 만들려고 빡세게 도입했다.**

#### 한줄 요약

- 데이터 보낼 때 정답 힌트(패리티)를 같이 보내서, 데이터가 깨져도 수신자가 스스로 강력히 고쳐내는 맷집 강화술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **부호율 (Code Rate)**: 전체 데이터 중에 '진짜 알맹이'가 차지하는 비율이다. 부호율을 낮추면 힌트가 많아져서 오류는 잘 잡지만 전송 속도는 떡락한다.
- **인터리버 (Interleaver)**: 전파가 끊겨서 데이터가 통째로 날아갈까 봐, 송신할 때 데이터를 카드 섞듯이 마구잡이로 섞어버려서 에러 피해를 분산시키는 꼼수 기술이다.

</details>

- **알맹이와 힌트의 눈치 게임 (부호율 제어)**: 데이터 10개 보낼 때 힌트를 5개 섞을지, 8개 섞을지 조절해서 '에러 방어력'과 '전송 대역폭 효율' 사이의 타협점을 찾는다.
- **카드 섞기 (인터리버 확산)**: 무선 환경에선 번개 맞고 데이터가 뭉텅이로 날아가니까(버스트 오류), 보낼 때 순서를 뒤죽박죽 섞어서 쏘고 받을 때 원상 복구시켜 에러를 산발적으로 흩뿌려버린다.
- **최소 거리 (Hamming Distance) 설계**: 부호들끼리의 최소 간격(거리)을 쫙 벌려놔서, 전파가 찌그러져도 "아 원래 이건 A라고 보낸 거구나" 하고 찰떡같이 알아먹게 설계한다.

#### 한줄 요약

- 부호율(힌트 양) 조절로 방어력을 키우고, 인터리버(카드 섞기)로 뭉텅이 오류를 흩뿌려서 에러 복원율을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **신드롬 (Syndrome)**: 받은 데이터가 멀쩡한지 계산해 보고, 결과값이 0이 아니면 "이거 어디 쪼가리가 깨졌다!" 하고 에러 위치를 찾아내는 체크 지표다.
- **CRC (순환 중복 검사)**: 에러 다 고치고 나서 최종적으로 "진짜 완벽하게 고쳐졌냐?" 하고 다항식 나눗셈으로 마지막 도장 찍는 깐깐한 검사관이다.

</details>

```text
[ 채널 코딩 직관적 비교 구조 ]

[ 1. 채널 부호기 ] ── (원본 데이터 옆에 힌트/패리티를 덕지덕지 붙임)
      │
      ▼
[ 2. 인터리버 ] ── (뭉텅이로 에러 날까 봐 데이터 순서를 마구 섞어버림)
      │
      ▼ (잡음 가득한 물리적 무선 채널 통과)
[ 3. 역인터리버 & 복호기 ] ── (섞인 거 풀고, 힌트 보고 깨진 비트 강력히 복구함)
      │
      ▼
[ 4. CRC 검사기 ] ── (완벽히 복구됐는지 최종 도장 쾅!)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **채널 부호기** | 원본 데이터 옆에 **"전파 깨지면 이거 보고 고쳐라" 하고 힌트 달아주는 놈** | Encoder |
| **인터리버** | 데이터 날아갈 때 통째로 뒤지지 않게 **순서를 뒤죽박죽 섞어버리는 타짜** | Interleaver |
| **잡음 채널** | 전파가 날아가면서 비바람 맞고 **비트가 0에서 1로 깨지는 물리적 무선 공간** | Channel |
| **복호기 (Decoder)** | 섞인 거 풀고, 힌트(신드롬) 계산해서 **깨진 비트 찾아내 강력히 원상 복구함** | Decoder |
| **CRC 검사기** | 복구 끝난 데이터에 **진짜 찌꺼기 없는지 다항식으로 최종 검사하는 판사** | Checker |

#### 한줄 요약

- 힌트 달고(부호기) $\to$ 순서 섞어서 쏘고(인터리버) $\to$ 수신자가 순서 풀고 오류 고친 뒤(복호기) $\to$ 최종 확인(CRC)하는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연판정 복호 (Soft Decision)**: "이거 0이야 1이야?" 무 자르듯 자르지 않고, "이건 70% 확률로 1 같네" 하고 아날로그 확률값(LLR)을 끝까지 살려서 복구 성공률을 높이는 극한의 쥐어짜기다.
- **HARQ (혼성 재전송)**: 스스로 복구하다가 정 안 돼서 다시 보내달라고 했을 때, 아까 버린 깨진 데이터랑 새로 받은 데이터를 합체(Combining)시켜서 기어이 살려내는 좀비 기술이다.

</details>

```text
[ 무선 전파 오류 복구 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [부호화 및 섞어서 발사]   │
│ (송신: 힌트 달고 카드 섞듯이 섞어서 전파 쏨)
└──────────────┬───────────────┘
               ▼ (비바람 맞고 데이터 깨짐)
┌──────────────────────────────┐
│ 2. [아날로그 확률값 수신]    │
│ (수신: 0인지 1인지 애매한 확률값(LLR) 일단 받음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [연판정 복호 (스스로 수리)] │
│ (수신: 힌트랑 확률값 뺑뺑이 돌려서 깨진 비트 살려냄)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [CRC 최종 검사 및 HARQ]   │
│ (판사: 멀쩡하면 패스! 실패하면 합체용 재전송 요청)
└──────────────────────────────┘
```

### 동작 원리

1. 부호화 및 인터리빙: 입력 비트에 패리티를 부가하여 부호어를 만든 뒤, 인터리버로 순서를 꼬아서 송신함.
2. 수신 신호 연판정 변환: 수신부는 물리 잡음이 섞인 전파를 받아서 비트별 애매한 확률값(LLR)으로 산출함.
3. 연판정 반복 복호: 확률값과 패리티 힌트를 가지고 터보 복호기가 뺑뺑이를 돌면서 원본 비트를 억지로 살려냄.
4. 잔여 오류 검사: 살려낸 비트를 순환 중복 검사(CRC)로 확인하고, 도저히 답 없으면 HARQ로 재전송받아 합체시킴.

#### 한줄 요약

- 확률값(연판정)으로 최대한 자체 수리해 보고, 안 되면 재전송받아서 기존 쓰레기랑 합쳐(HARQ) 기어이 살려내는 독한 놈이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **해밍 부호 / 리드-솔로몬 / 터보 부호**: 해밍은 비트 딱 1개 고치는 가벼운 기본 부호, 리드-솔로몬은 뭉텅이로 날아간 거 복구하는 부호, 터보는 섀넌 한계까지 복구해 내는 5G용 끝판왕 부호다.

</details>

| 구분 | **해밍 부호 (Hamming)** | **리드-솔로몬 부호 (RS Code)** | **터보 부호 (Turbo / LDPC)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | 비트 1개만 고치는 **구급상자** | 뭉텅이로 찢어진 거 기워주는 **수술실** | 극한까지 살려내는 **LTE/5G 중환자실** |
| 주요 정정 타겟 | **단일 비트** 1개 깨진 거 | 뭉텅이로 박살 난 **버스트 오류** | 무선 채널의 **무작위 쌉노이즈 오류** |
| 복구 한계 및 성능 | 계산은 가볍지만 **방어력 허접함** | 블록 단위 연산으로 **중간 방어력** | 수학적 한계(섀넌) 도달하는 **우주 최강 방어력** |
| 주력 사용처 | 서버용 **ECC RAM 메모리**, L1 캐시 | 기스 난 **CD/DVD, 바코드, QR코드** | **3G/4G/5G 스마트폰**, 심우주 위성 통신 |

#### 한줄 요약

- 가벼운 메모리엔 해밍 부호, 뭉텅이로 깨지는 바코드나 CD엔 RS 부호, 노이즈 쩌는 5G 무선 통신엔 터보/LDPC 부호를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **BLER (블록 오류율)**: 보낸 데이터 묶음(블록) 중에 CRC 검사 통과 못하고 박살 나서 버려진 쓰레기 블록들의 비율이다.
- **적응형 부호화 (AMC)**: 날씨 좋고 신호 빵빵하면 힌트 줄이고 속도 올리고, 터널 들어가서 신호 구려지면 속도 줄이고 힌트를 덕지덕지 발라서 살아남는 눈치 게임 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 터널 들어갔더니 **데이터가 통째로 박살 남 (BLER 폭증)** | 페이딩 심해졌는데 힌트(패리티) 없이 속도만 올리려다 에러 오지게 터짐 | 실시간으로 신호 눈치 보며 힌트(부호율) 조절하는 **적응형 부호화(AMC) 가동** | 전파 상태 구려도 강력히 통신 유지력 끈질기게 방어 |
| 무선 에러는 다 잡았는데 **핑(지연 시간)이 오지게 튐** | 터보 부호가 확률 계산한답시고 복호기 뺑뺑이(반복)를 너무 오랫동안 돌림 | 반복 복호 횟수에 **상한선(Limit) 걸거나, 연산 가벼운 LDPC로 전면 교체** | 복호 연산 딜레이 컷트하고 초저지연(URLLC) 속도 보장 |
| 스마트폰으로 통신 좀 했다고 **배터리가 30분 만에 녹아내림** | 확률값 계산(LLR)하고 에러 복구하는 수학 연산에 폰 CPU를 갈아 넣음 | 패킷 뜯고 복원하는 건 무조건 **하드웨어 전용 칩(ASIC/가속기)에 짬처리시킴** | 단말기 발열 잡고 5G 배터리 광탈 원천 차단 |

#### 한줄 요약

- 신호 구려지면 눈치껏 힌트(AMC) 늘리고, 핑 튀면 뺑뺑이 그만 돌리고, 폰 배터리 타니까 연산은 전용 칩에 떠넘겨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 열악하고 불안정한 무선 채널 환경에서 재전송 지연(Latency)을 최소화하기 위해, **FEC 순방향 오류 정정** 및 **연판정 반복 복호** 활용 결합하여 섀넌 한계에 근접하는 채널 코딩 기조 확립함

#### 한줄 요약

- 채널 코딩은 노이즈로 박살 난 쓰레기 데이터를 수학과 확률의 힘으로 멱살 잡아 끌어올리는 통신계의 심폐소생술이다.
