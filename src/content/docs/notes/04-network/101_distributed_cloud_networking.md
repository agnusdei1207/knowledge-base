## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Distributed Cloud Networking**: 퍼블릭 클라우드, 온프레미스, 분산 엣지 인프라를 단일 오버레이로 연결하고 중앙에서 제어하는 네트워크.
- **Data Sovereignty (데이터 주권)**: 특정 국가/지역(EU GDPR 등) 내에서 생성된 데이터의 역외 유출을 금지하고 현지 처리를 강제하는 규제.

</details>

- 정의/개념: 분산 엣지 및 멀티클라우드 환경에서 **선언적 중앙 제어 평면과 엣지 집행 게이트웨이로 초저지연 경로와 데이터 주권을 보장하는 네트워크 아키텍처**
- 배경/필요성: 중앙 집중형 클라우드의 장거리 WAN 전송 한계로 인한 **전송 지연 증가, 지역별 데이터 주권(GDPR) 규제 위반 및 엣지 관리 파편화**

#### 한줄 요약
- 중앙 선언적 거버넌스와 엣지 분산 집행을 통해 초저지연 연결과 데이터 주권을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Overlay-Underlay Decoupling**: 하부 물리 전송망(ISP/5G Underlay)과 무관하게 가상 오버레이(SRv6/WireGuard)로 독립된 멀티 테넌트 통신을 제공하는 분리 구조.
- **Local Data In-situ Processing**: 민감 데이터를 중앙으로 가져오지 않고 데이터가 발생한 현장 엣지에서 즉시 연산·처리하는 기법.

</details>

- **중앙 선언적 제어 및 분산 데이터 평면**: 단일 제어 평면에서 정의된 정책을 **전 세계 분산 엣지 게이트웨이에서 일관 집행**
- **현지 완결형 초저지연 처리($\le 10\text{ms}$)**: 사용자 근접 엣지에서 트래픽을 즉시 종단·연산하여 **응답 속도 극대화**
- **엄격한 데이터 주권(Data Sovereignty) 보장**: 국가별 개인정보보호 규제에 따라 **지정된 관할 지역(Jurisdiction) 내 데이터 격리**

#### 한줄 요약
- 중앙 선언적 통제, 현지 완결형 초저지연, 데이터 주권 기반 지리적 격리를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SRv6 (Segment Routing over IPv6)**: IPv6 확장 헤더에 세그먼트 리스트를 정의하여 엣지 간 오버레이 경로와 네트워크 슬라이싱을 유연하게 제어하는 라우팅 기술.

</details>

```text
[분산 클라우드 네트워킹 E2E 아키텍처]
|-- Central Control Plane (중앙 제어 평면: Intent Engine, Global Anycast GSLB, Drift Verifier)
`-- Region A Edge Gateway (EU Region: SRv6 오버레이 종단, EU 로컬 데이터 주권 격리)
    `-- Local K8s Edge Cluster (현지 완결형 초저지연 워크로드)
`-- Region B Edge Gateway (US Region: SRv6 오버레이 종단, L7 캐싱 및 인스펙션)
    `-- Local K8s Edge Cluster (현지 완결형 초저지연 워크로드)
```

선의 의미: 중앙 제어 평면의 정책 의도가 각 지역 엣지 게이트웨이로 배포되어 오버레이 터널링과 데이터 주권 라우팅이 분산 집행되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **중앙 제어 평면** | 전사 토폴로지 관리, **인텐트 정책 컴파일, 엣지 게이트웨이 구성 배포** | Control Plane |
| **정책 엔진** | 사용자 신원, 데이터 분류, **지리적 주권 요건을 대조하여 라우팅 정책 산출** | Policy Engine |
| **지역 엣지 게이트웨이**| 멀티 테넌트 **오버레이 터널 종단, 패킷 필터링, 로컬 스티어링 집행** | Data Plane Edge |
| **전역 서비스 발견기** | 글로벌 **Anycast DNS 및 Geo-IP 기반으로 요청을 최적 엣지로 전달** | Global GSLB |
| **관측 및 드리프트 검증기**| 전 지역 엣지의 실제 라우팅 상태를 수집하여 **선언 정책과의 일치성 검증** | Continuous Audit |

#### 한줄 요약
- 중앙 제어 평면, 정책 엔진, 엣지 게이트웨이, 전역 서비스 발견기, 관측 검증기가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Closed-Loop Resync (폐루프 정책 재동기화)**: 관측 엔진이 특정 엣지의 정책 누락(Drift)을 감지했을 때 즉시 최신 구성을 강제 재주입하여 정합성을 복구하는 메커니즘.

</details>

```text
분산 클라우드 인텐트 선언, 엣지 배포 및 데이터 주권 라우팅 파이프라인
        │
   1. [보안 인텐트 선언] 운영자가 'EU 거주자 금융 데이터의 역외 유출 금지' 인텐트를 선언
        │
   2. [정책 컴파일 및 배포] 중앙 제어기가 SRv6/IPsec 라우팅 룰을 생성하여 엣지 게이트웨이로 배포
        │
   3. [로컬 엣지 종단 처리] EU 사용자 요청은 EU 엣지 로컬 클라우드에서 즉시 종단 및 10ms 내 연산
        │
   4. [지속적 드리프트 감사] 관측 계층이 엣지 노드의 실제 포워딩 테이블을 실시간 감사
        │
   ├─ [정책 드리프트 감지 시] ➔ 중앙 제어기가 해당 엣지에 정책 강제 재동기화(Resync)
   ▼
5. [데이터 주권 준수 확정] 지연 시간 10ms 이하 처리 및 역외 유출 차단 100% 보증
```

#### 한줄 요약
- 인텐트 선언 → 분산 정책 배포 → 로컬 엣지 처리 → 연속 드리프트 감사 → 자동 재동기화 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Distributed Cloud** vs **Multi-Cloud** vs **Centralized Cloud**.

</details>

| 비교 항목 | 분산 클라우드 네트워킹 (Distributed Cloud) | 멀티 클라우드 네트워킹 (Multi-Cloud) | 중앙 집중형 클라우드 (Centralized) |
|:---|:---|:---|:---|
| **아키텍처 구조** | **중앙 통제 + 글로벌 분산 엣지(Edge) 통합**| **이종 CSP(AWS, Azure, GCP) 간 상호 연결** | **소수 중앙 대형 데이터센터 리전 집중** |
| **제어 및 운영** | **단일 제어 평면에서 전 엣지 통합 거버넌스** | CSP별 상이한 네트워크 스택 개별 연동 | 중앙 리전 중심 단순 운영 |
| **지연 시간 (Latency)**| **초저지연 ($\le 10\text{ms}$ 사용자 근접 완결)** | 네트워크 홉 수 증가로 중간 수준 | 장거리 WAN 전송으로 높은 지연 발생 |
| **데이터 주권 준수** | **우수 (지역 엣지 고정 처리 완벽 지원)** | CSP 리전별 정책 조합으로 복잡 | 역외 데이터 이전 위험 상존 |
| **주요 적용 분야** | **스마트 모빌리티, 스마트팩토리, 글로벌 SaaS**| **벤더 락인 방지, 재해 복구(DR) 다중화** | 전통적 전사 ERP, 대규모 배치 연산 |

#### 한줄 요약
- 분산 클라우드는 초저지연과 데이터 주권, 멀티 클라우드는 벤더 다변화, 중앙 클라우드는 단순 관리에 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Geo-Tagging (지리적 제약 태그)**: 패킷 헤더에 데이터 생성 지역 태그를 부착하여 라우터가 지정된 국경 경계를 벗어나는 경로로 패킷을 전달하지 못하도록 막는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 엣지 통신 불안정으로 중앙 정책 미반영 및 **지역별 정책 드리프트 발생** | **`GitOps 기반의 선언적 구성 동기화` 및 주기적 상태 감사(Audit)** | 엣지 정책 일치율 100% 확보 및 보안 사각지대 제거 |
| 동적 우회 라우팅 시 민감 데이터가 타국 리전으로 넘어가는 **데이터 주권 위반** | 패킷 헤더에 **`지리적 제약 태그(Geo-Tag)` 부여 및 이탈 불가 바운더리 라우팅** | 역외 데이터 유출 원천 차단 및 GDPR 규제 완벽 준수 |
| 엣지와 중앙 클라우드 간 원시 데이터 전송으로 인한 WAN 회선 비용 폭증 | **`엣지 현지 완결형 전처리(Local Processing)` 및 결과값만 집약 전송** | WAN 대역폭 비용 70% 절감 및 실시간 응답성 극대화 |
| 수백 개 분산 엣지 간 메시 터널링 수동 구성의 운영 복잡성 한계 | **`SDN 오버레이 기반 자동 풀메시 터널(Auto-Tunneling)` 오케스트레이션** | 엣지 노드 추가 시 제로터치 프로비저닝(ZTP) 달성 |

#### 한줄 요약
- GitOps로 정책 드리프트를 방지하고, Geo-Tag로 데이터 주권을 수호하며, 엣지 현지 처리로 전송 비용을 절감한다.

## Ⅶ. 결론

- 글로벌 엣지 컴퓨팅 및 하이브리드 워크로드의 확산에 대응하여 **분산 클라우드 네트워킹 아키텍처를 엔터프라이즈 표준으로 구축**하되, 운영 복잡성과 보안 리스크를 통제하기 위해 **선언적 중앙 제어 평면, SRv6/WireGuard 기반 초저지연 오버레이, 지속적 정책 드리프트 감사 및 자가 치유, 데이터 주권 기반의 지리적 라우팅 통제**를 통합 구현하여 신뢰성 높은 글로벌 분산 네트워크 인프라 완성

#### 한줄 요약
- 분산 클라우드 네트워킹은 선언적 중앙 거버넌스와 엣지 로컬 완결형 처리를 결합하여 초저지연과 데이터 주권을 동시에 달성하는 인프라다.
