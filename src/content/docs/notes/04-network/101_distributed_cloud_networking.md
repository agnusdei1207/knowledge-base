## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Distributed Cloud Networking**: 퍼블릭 클라우드, 온프레미스, 분산 엣지 인프라를 단일 오버레이로 연결하고 중앙에서 제어하는 네트워크.
- **Data Sovereignty (데이터 주권)**: 특정 국가/지역(EU GDPR 등) 내에서 생성된 데이터의 역외 유출을 금지하고 현지 처리를 강제하는 규제.

</details>

- 정의/개념: 중앙 정책과 엣지 집행으로 **저지연·데이터 주권**을 보장하는 구조
- 배경/필요성: 중앙 클라우드의 장거리 WAN으로 **지연·주권·관리 제약** 발생

#### 한줄 요약
- 중앙 선언적 거버넌스와 엣지 분산 집행을 통해 초저지연 연결과 데이터 주권을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Overlay-Underlay Decoupling**: 하부 물리 전송망(ISP/5G Underlay)과 무관하게 가상 오버레이(SRv6/WireGuard)로 독립된 멀티 테넌트 통신을 제공하는 분리 구조.
- **Local Data In-situ Processing**: 민감 데이터를 중앙으로 가져오지 않고 데이터가 발생한 현장 엣지에서 즉시 연산·처리하는 기법.

</details>

- **중앙 제어·분산 집행**: 동일 정책을 전 지역 엣지에서 집행
- **현지 완결 처리**: 사용자 근접 엣지에서 10ms 내 처리
- **데이터 주권**: 지정 관할 지역 안에 데이터 격리

#### 한줄 요약
- 중앙 선언적 통제, 현지 완결형 초저지연, 데이터 주권 기반 지리적 격리를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SRv6 (Segment Routing over IPv6)**: IPv6 확장 헤더에 세그먼트 리스트를 정의하여 엣지 간 오버레이 경로와 네트워크 슬라이싱을 유연하게 제어하는 라우팅 기술.

</details>

```text
[분산 클라우드 정적 구성]
|-- 중앙 제어 평면
|-- 정책 엔진
|-- 지역 엣지 게이트웨이
|-- 전역 서비스 발견기
`-- 관측 및 드리프트 검증기
```

선의 의미: 중앙 제어 평면의 정책 의도가 각 지역 엣지 게이트웨이로 배포되어 오버레이 터널링과 데이터 주권 라우팅이 분산 집행되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| 중앙 제어 평면 | **인텐트 컴파일·구성 배포** | Control Plane |
| 정책 엔진 | **주권 기반 라우팅 정책 산출** | Policy Engine |
| 지역 엣지 게이트웨이 | **오버레이 종단·로컬 스티어링** | Data Plane Edge |
| 전역 서비스 발견기 | **Anycast·Geo-IP 엣지 선택** | Global GSLB |
| 관측 및 드리프트 검증기 | **실제 상태·선언 정책 비교** | Continuous Audit |

#### 한줄 요약
- 중앙 제어 평면, 정책 엔진, 엣지 게이트웨이, 전역 서비스 발견기, 관측 검증기가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Closed-Loop Resync (폐루프 정책 재동기화)**: 관측 엔진이 특정 엣지의 정책 누락(Drift)을 감지했을 때 즉시 최신 구성을 강제 재주입하여 정합성을 복구하는 메커니즘.

</details>

```text
운영자 인텐트
    |
1. 보안 인텐트 선언
    |
2. 정책 컴파일·배포
    |
3. 로컬 엣지 처리
    |
4. 드리프트 감사
    +-- 불일치: 정책 재동기화
    |
5. 주권 준수 검증
    |
감사 결과
```

- 1. 보안 인텐트 선언
- 2. 정책 컴파일·배포
- 3. 로컬 엣지 처리
- 4. 드리프트 감사
- 5. 주권 준수 검증

#### 한줄 요약
- 인텐트 선언 → 분산 정책 배포 → 로컬 엣지 처리 → 연속 드리프트 감사 → 자동 재동기화 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Distributed Cloud** vs **Multi-Cloud** vs **Centralized Cloud**.

</details>

| 비교 항목 | 분산 클라우드 네트워킹 (Distributed Cloud) | 멀티 클라우드 네트워킹 (Multi-Cloud) | 중앙 집중형 클라우드 (Centralized) |
|:---|:---|:---|:---|
| 아키텍처 구조 | **중앙 통제·분산 엣지** | **이종 CSP 연결** | **중앙 리전 집중** |
| 제어 및 운영 | **단일 거버넌스** | CSP별 연동 | 중앙 운영 |
| 지연 시간 | **10ms 이하** | 중간 | 높음 |
| 데이터 주권 준수 | **지역 고정 처리** | 리전별 조합 | 역외 이전 위험 |
| 주요 적용 분야 | **모빌리티·공장·SaaS** | **락인 방지·DR** | ERP·배치 연산 |

#### 한줄 요약
- 분산 클라우드는 초저지연과 데이터 주권, 멀티 클라우드는 벤더 다변화, 중앙 클라우드는 단순 관리에 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Geo-Tagging (지리적 제약 태그)**: 패킷 헤더에 데이터 생성 지역 태그를 부착하여 라우터가 지정된 국경 경계를 벗어나는 경로로 패킷을 전달하지 못하도록 막는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 통신 불안정에 따른 정책 드리프트 | **GitOps 동기화·상태 감사** | 정책 일관성 확보 |
| 우회 경로의 데이터 주권 위반 | **Geo-Tag·경계 라우팅** | 역외 유출 차단 |
| 원시 데이터 전송 비용 증가 | **엣지 전처리·결과 전송** | WAN 비용 절감 |
| 다수 엣지의 터널 구성 복잡성 | **SDN 자동 터널링** | ZTP 확장 |

#### 한줄 요약
- GitOps로 정책 드리프트를 방지하고, Geo-Tag로 데이터 주권을 수호하며, 엣지 현지 처리로 전송 비용을 절감한다.

## Ⅶ. 결론

- 저지연·주권 요구는 **분산 엣지**, 단순 운영은 **중앙 클라우드** 선택

#### 한줄 요약
- **중앙 거버넌스·현지 처리**로 지연과 주권 균형
