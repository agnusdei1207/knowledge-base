## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Subnetting (서브네팅)**: 단일 네트워크 주소 공간을 호스트 비트를 빌려 복수의 더 작은 서브넷(Subnet)으로 분할하는 기술.
- **CIDR (Classless Inter-Domain Routing)**: 기존의 클래스(Class A/B/C) 개념을 폐지하고, 슬래시 표기법(`/N`)을 사용하여 필요한 크기만큼 유연하게 주소를 할당하고 집약(Supernetting)하는 라우팅 기술.

</details>

- 정의/개념: IP 주소 공간의 낭비를 최소화하고 라우팅 테이블 크기를 최적화하기 위해 **네트워크를 유연하게 분할(Subnetting)하고 공통 프리픽스로 집약(CIDR)하는 주소 관리 기술**
- 배경/필요성: 클래스 고정 경계로 **주소 낭비와 경로 증가** 발생

#### 한줄 요약
- VLSM 기반의 미세 주소 분할과 CIDR 프리픽스 집약을 통해 주소 효율과 라우팅 확장성을 확보한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VLSM (Variable Length Subnet Mask)**: 동일 네트워크 내에서 서브넷마다 서로 다른 길이의 서브넷 마스크를 적용하여 호스트 요구량에 최적화하는 기법.
- **Supernetting (경로 집약 / Route Aggregation)**: 연속된 복수의 서브넷 경로를 공통 상위 프리픽스를 가진 단일 경로로 축약하여 광고하는 기법.

</details>

- 클래스 경계 없이 임의의 비트 단위로 주소를 할당하는 **클래스리스(Classless) 주소 지정**
- 부서별 호스트 규모에 맞추어 마스크 길이를 가변 적용하는 **가변 길이 서브넷 마스크(VLSM)**
- 연속된 서브넷 블록을 단일 상위 경로로 묶어 라우터 메모리를 절감하는 **경로 집약(Supernetting)**

#### 한줄 요약
- 클래스리스 할당, VLSM 가변 분할, Supernetting 경로 집약을 통해 네트워크를 최적화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **서브넷 주소 계산 구조**: $N$비트 네트워크 프리픽스 + $H$비트 호스트 비트 ($N + H = 32$). 유효 호스트 수는 $2^H - 2$ (네트워크 ID와 브로드캐스트 주소 제외).

</details>

```text
[IPv4 CIDR 블록]
|-- 네트워크 프리픽스
`-- 호스트 비트
    |-- 네트워크 주소
    |-- 유효 호스트 주소
    `-- 브로드캐스트 주소
```

선의 의미: 계층 및 32비트 IP 주소에서 서브넷 마스크에 의해 네트워크 식별자와 호스트 식별자로 분할되는 구조

| 구성요소 | 책임 |
|:---|:---|
| **네트워크 프리픽스** | 목적지 서브넷 식별과 LPM 기준 제공 |
| **호스트 비트** | 서브넷 내부 단말 식별 |
| **유효 호스트 범위** | 할당 가능한 호스트 주소 제공 |
| **경로 집약** | 연속 하위 경로를 상위 경로로 축약 |

#### 한줄 요약
- 네트워크 프리픽스, 호스트 비트, 유효 호스트 범위, 경로 집약이 상호 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **VLSM 설계 5단계**: 부서별 필요 호스트 산정 $\to$ 수요 내림차순 정렬 $\to$ 서브넷 마스크 할당 $\to$ 연속 주소 부여 $\to$ CIDR 집약 광고.

</details>

```text
1. 수요 산정
      |
2. 내림차순 정렬
      |
3. 블록 크기 할당
      |
4. 연속 주소 배치
      |
5. 경로 집약
```

- 1. 수요 산정: 서브넷별 호스트 요구량 집계
- 2. 내림차순 정렬: 큰 주소 블록부터 배치
- 3. 블록 크기 할당: 요구량을 만족하는 **프리픽스** 선정
- 4. 연속 주소 배치: 경계에 맞춰 블록 할당
- 5. 경로 집약: 공통 프리픽스로 경로 광고

#### 한줄 요약
- 수요 산정 → 내림차순 정렬 → 블록 크기 할당 → 연속 배치 → CIDR 축약 광고 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Subnetting vs Supernetting (CIDR Aggregation)**: 큰 네트워크를 작게 분할하는 서브네팅과 작은 서브넷들을 크게 통합하는 슈퍼네팅.

</details>

| 비교 항목 | 서브네팅 (Subnetting) | CIDR 경로 집약 (Supernetting) |
|:---|:---|:---|
| 작업 방향 | 대형 네트워크를 소형 서브넷으로 분할 | 소형 서브넷을 상위 경로로 집약 |
| 프리픽스 변화 | **프리픽스 길이 증가** | **프리픽스 길이 감소** |
| 적용 위치 | 사내망·데이터센터·VPC | 백본·BGP 경로 광고 |
| 목적 | 주소 효율과 브로드캐스트 격리 | 라우팅 테이블 축소 |
| 전제 조건 | 호스트 수와 블록 경계 일치 | 주소 블록의 연속성과 경계 일치 |

#### 한줄 요약
- 사내 망에서는 서브네팅으로 세분화하고, 코어 라우팅 광고 시에는 슈퍼네팅으로 경로를 축약한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Broadcast Domain Isolation (브로드캐스트 도메인 격리)**: 과도한 L2 브로드캐스트 트래픽이 전체 네트워크 장비의 CPU를 고갈시키는 브로드캐스트 스톰을 방지하기 위해 서브넷을 분할하는 조치.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 서브넷 크기 과다로 인한 브로드캐스트 스톰 발생 | **브로드캐스트 도메인을 `/24` (254개) 이하 크기로 세분화 서브네팅** | L2 트래픽 오버헤드 격리 및 스위치 보호 |
| 주소 여유 없이 설계하여 향후 조직 확장 시 IP 고갈 | **향후 30~50% 확장을 고려한 `용량 산정(Capacity Planning)` 반영** | 대규모 네트워크 주소 재설계 방지 |
| 비연속적 IP 할당으로 인한 CIDR 경로 집약 실패 및 라우터 과부하 | **IPAM 솔루션을 활용하여 조직별 주소를 `연속된 블록(Contiguous)`으로 배치** | BGP 라우팅 테이블 축약 성공률 100% 달성 |
| 클라우드 VPC 서브넷 간 IP 중복으로 인한 VPN/피어링 연결 불가 | **전사 하이브리드 클라우드 `단일 IP 대역 관리 거버넌스(IPAM)` 구축** | 서브넷 IP 충돌 원천 방지 |

#### 한줄 요약
- 브로드캐스트 도메인 격리, 확장 용량 산정, 연속 블록 할당, IPAM 거버넌스로 운영한다.

## Ⅶ. 결론

- 호스트별 분할은 **VLSM**, 연속 경로 축약은 CIDR 집약

#### 한줄 요약
- 서브네팅과 CIDR은 주소 공간의 미세 분할과 경로 집약을 통해 IP 자원 활용률을 극대화하고 라우팅 부하를 절감하는 핵심 네트워크 설계 기술이다.
