## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **서브네팅(Subnetting)**: 단일 IP 주소 블록을 더 긴 프리픽스를 가진 여러 개의 작은 논리적 네트워크로 분할하는 기법.
- **클래스 없는 도메인 간 라우팅(Classless Inter-Domain Routing, CIDR)**: 기존의 클래스(A/B/C) 개념을 탈피하여 임의의 프리픽스 길이로 주소 할당 및 라우팅 경로를 집약하는 기법.

</details>

- 정의/개념: 주소 블록을 효율적으로 분할하는 **서브네팅(Subnetting)**과 프리픽스 기반 라우팅을 집약하는 **CIDR(Classless Inter-Domain Routing)**.
- 배경/필요성: 고정 클래스 주소 할당에 따른 주소 공간 낭비 방지 및 백본 라우터의 라우팅 테이블 폭발적 증가 억제.

#### 한줄 요약

- 큰 주소 구역을 필요한 크기로 나누고 공통 앞자리는 하나의 경로로 묶는다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **프리픽스 길이(Prefix Length)**: IP 주소에서 네트워크 영역을 나타내는 상위 비트의 수.
- **가변 길이 서브넷 마스크(Variable Length Subnet Mask, VLSM)**: 하나의 네트워크 주소 공간 내에서 서브넷마다 서로 다른 크기의 마스크를 적용하는 주소 설계 방식.
- **경로 집약(Route Aggregation)**: 연속된 다수의 하위 라우팅 경로를 하나의 상위 공통 프리픽스로 축약하여 광고하는 기법.

</details>

![프리픽스 증가에 따른 서브넷 수와 주소 블록 크기의 상충](/study/diagrams/cidr-subnet-tradeoff.svg)

> `/24`를 같은 크기로 분할한 파란 선은 생성 서브넷 수, 붉은 선은 서브넷당 주소 블록 크기의 정규화 비율이며 `/26`에서는 4개 서브넷과 각 64개 주소가 되는 관계를 나타냄.

- **프리픽스 길이(Prefix Length)** 증가에 따른 호스트 주소 수 및 브로드캐스트 범위의 축소.
- **가변 길이 서브넷 마스크(Variable Length Subnet Mask, VLSM)**를 활용한 서브넷별 효율적 주소 할당 및 낭비 최소화.
- **경로 집약(Route Aggregation)**을 통한 전체 라우팅 테이블 엔트리 수 절감.

#### 한줄 요약

- 주소 앞부분을 더 길게 네트워크 이름으로 쓰면 장치에 나눠 줄 뒷부분이 줄어든다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **서브넷 마스크(Subnet Mask)**: IP 주소에서 네트워크 영역과 호스트 영역을 구분하기 위해 사용하는 32비트 마스크 패턴.
- **네트워크 프리픽스(Network Prefix)**: 주소 공간에서 특정 서브넷 또는 네트워크 전체를 식별하는 상위 비트열.
- **호스트 비트(Host Bits)**: 서브넷 내부에서 개별 호스트 및 인터페이스를 식별하는 하위 비트열.
- **호스트 범위(Host Address Range)**: 네트워크 주소와 브로드캐스트 주소를 제외하고 실제 장비에 할당 가능한 유효 IP 주소 구간.

</details>

```text
집약 경로
└── 주소 블록
    ├── 네트워크 프리픽스
    └── 호스트 비트
```

선의 의미: 네트워크 프리픽스와 호스트 비트로 구성된 주소 블록의 하위 분할 및 상위 경로 집약 관계 표시.

| 구성요소 | 책임 |
|:---|:---|
| 네트워크 프리픽스 | **서브넷 마스크(Subnet Mask)**를 이용한 서브넷 범위 식별 |
| 호스트 비트 | **호스트 비트(Host Bits)** 할당을 통한 유효 **호스트 범위(Host Address Range)** 산정 |
| 집약 경로 | 공통 프리픽스 추출 기반 **경로 집약(Route Aggregation)** 수행 |

#### 한줄 요약

- `/24` 구역을 `/26`으로 나누면 네 구역이 생기고 외부에는 다시 `/24` 하나로 알릴 수 있다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **인터넷 프로토콜 주소 관리(Internet Protocol Address Management, IPAM)**: IP 주소 공간의 할당, 서브네팅, DNS/DHCP 통합 관리를 자동화하는 체계.
- **집약 프리픽스(Aggregated Prefix)**: 여러 하위 서브넷 블록의 공통 비트열을 대표하는 상위 라우팅 프리픽스.
- **프리픽스 산정(Prefix Calculation)**: 호스트 수 및 2비트 예비 공간을 고려한 최소 주소 블록의 프리픽스 계산 과정.
- **수요 내림차순 정렬(Descending Demand Sorting)**: 서브넷 할당 시 가장 큰 주소 블록 수요부터 우선 배치하는 설계 절차.
- **블록 경계 배치(Boundary Placement)**: 2^n 단위의 프리픽스 경계에 맞추어 주소를 할당하고 중복을 방지하는 작업.
- **집약 경로 생성(Aggregate Route Generation)**: 연속된 서브넷 블록의 공통 프리픽스를 도출하여 상위 경로를 형성하는 절차.

</details>

```text
호스트 수요•증가율
        |
        v
1. 프리픽스 산정
        |
        `-- IPv4: 2^h >= 호스트 수+2, /32-h
                         |
                         v
2. 수요 내림차순 정렬
                         |
                         v
3. 블록 경계 배치
                         |
                         +-- 중복•상위 범위 초과 ---- 재산정
                         |
                         `-- 경계 적합
                                |
                                v
                       4. 집약 경로 생성
                                |
                                +-- 연속•공통 프리픽스 ---- 집약
                                `-- 비연속 --------------- 개별 경로
```

### 동작 원리

1. **프리픽스 산정(Prefix Calculation)**: 호스트 수요 수용을 위한 최소 블록 크기 계산.
2. **수요 내림차순 정렬(Descending Demand Sorting)**: 대용량 블록 우선 할당 프로세스 수행.
3. **블록 경계 배치(Boundary Placement)**: 주소 경계 유효성 및 중복 여부 점검.
4. **집약 경로 생성(Aggregate Route Generation)**: 연속 서브넷 대상 **집약 프리픽스(Aggregated Prefix)** 추출 및 축약 라우팅 생성.

#### 한줄 요약

- 큰 부서 주소부터 정확한 경계에 놓아야 작은 부서 공간이 잘리지 않고 경로도 묶을 수 있다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **서브넷(Subnet)**: 하나의 커다란 네트워크를 효율적 관리를 위해 분할한 단일 브로드캐스트 도메인 단위.
- **가변 프리픽스(Variable Prefix)**: 클래스 경계에 얽매이지 않고 임의의 비트 단위로 부여되는 프리픽스 표기 방식.

</details>

| 주소 설계 방식 | **서브네팅** | **CIDR** |
|:---|:---|:---|
| 적용 기준 | 내부 브로드캐스트 범위 분리 | 주소 할당•외부 **경로 집약** |
| 핵심 특징 | 하나의 **서브넷**을 여러 하위 망으로 분할 | **가변 프리픽스**로 블록•경로 표현 |
| 한계 | 작은 블록의 조기 고갈 | 비연속 블록의 집약 불가 |

> 요약: 내부 망 분할 중심의 서브네팅과 외부 라우팅 경로 집약 중심의 CIDR 역할 비교.

#### 한줄 요약

- 서브네팅은 내부 구역을 나누고 CIDR은 크기가 다른 주소 구역과 경로를 표현한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **주소 재설계(Address Redesign)**: 주소 고갈 또는 충돌 발생 시 전체 IP 할당 체계를 재구성하는 고비용 재작업.
- **브로드캐스트 도메인(Broadcast Domain)**: 브로드캐스트 프레임 전파가 미치는 데이터 링크 계층 논리적 영역.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 현재 호스트 수만 반영해 블록 조기 고갈 | 성장률•예비 주소를 포함한 수요 산정 | **주소 재설계(Address Redesign)** 방지 |
| 하위 블록이 비연속으로 배정 | 큰 블록부터 연속 배치 | **경로 집약(Route Aggregation)** 가능 |
| 여러 조직이 같은 서브넷을 중복 할당 | **IPAM** 중복•경계 검사 자동화 | 주소 충돌 예방 |
| 대형 서브넷에 브로드캐스트가 집중 | **브로드캐스트 도메인(Broadcast Domain)**과 보안 경계 분리 | 장애 영향 범위 축소 |

#### 한줄 요약

- 클라우드 네트워크는 큰 확장 구역부터 연속 배치해야 나중에 주소를 다시 옮기지 않고 경로를 묶을 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **주소 수요 산정(Address Capacity Planning)**: 시스템 성장률 및 인프라 확장을 감안한 서브넷 필요 크기 계산 프로세스.
- **주소 블록 결정(Address Block Selection)**: 요구되는 호스트 수와 라우팅 집약 효율을 고려하여 최종 주소 영역을 확정하는 의사결정.

</details>

- **주소 수요 산정(Address Capacity Planning)**을 통한 필요 서브넷 크기 계산 및 **주소 블록 결정(Address Block Selection)**에 기초한 CIDR 라우팅 집약 전략 수립.

#### 한줄 요약

- 현재 장치 수와 확장 공간, 묶어 광고할 경계를 함께 보고 주소 블록을 정해야 한다.
