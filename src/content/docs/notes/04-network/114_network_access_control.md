## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 접근 제어(Network Access Control, NAC)**: 사내 유무선 네트워크에 접속을 시도하는 모든 엔드포인트 단말에 대해 사용자 신원 인증뿐만 아니라 단말의 보안 상태(OS 패치, 백신 구동, 필수 에이전트 설치 여부)를 검증하여, 보안 정책을 충족한 단말에만 업무망 접속을 허용하고 비인가/취약 단말은 격리망(Quarantine VLAN)으로 통제하는 보안 솔루션.
- **포스처 점검(Posture Assessment)**: 단말의 레지스트리, 프로세스, OS 업데이트 버전, 백신 바이러스 패턴 최신성, 디스크 암호화 여부 등을 스캔하여 사내 보안 규정 준수율을 평가하는 사전/사후 무결성 검증 프로세스.

</details>

- 정의/개념: 단말의 **사전 인증 및 무결성 검증(Pre-Admission)**, 비준수 단말의 **동적 격리 및 자동 치료(Remediation)**, 접속 후 이상 행위를 감시하는 **사후 통제(Post-Admission)** 를 통해 엔드포인트 위협의 내부망 유입을 원천 차단하는 **엔터프라이즈 네트워크 접근 통제 아키텍처**
- 배경/필요성: BYOD(Bring Your Own Device) 및 원격 근무 확산으로 악성코드에 감염된 취약한 개인 노트북이나 인가되지 않은 비관리(Shadow IoT) 기기가 사내망에 직결되어 내부 횡적 이동(Lateral Movement)을 유발하는 보안 사각지대를 해소할 요구

#### 한줄 요약
- 사용자 신원과 단말의 무결성을 사전 검증하고 동적 VLAN/ACL로 격리 및 치료를 집행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **동적 VLAN(Dynamic VLAN) 및 동적 ACL(dACL)**: RADIUS 서버의 인증 결과에 따라 네트워크 스위치/AP 포트의 VLAN ID(업무망, 게스트망, 격리망)를 실시간 변경하고, 허용 포트/IP를 제한하는 다운로드형 접근 제어 목록(dACL).
- **에이전트 기반(Agent-based) vs 에이전트리스(Agentless)**: 전용 소프트웨어를 설치하여 심층 포스처를 점검하는 방식과, SNMP/DHCP 핑거프린팅/포털 인증으로 네트워크 레벨에서 기기를 식별·통제하는 방식.

</details>

- **사전 검증(Pre-Admission)과 사후 감시(Post-Admission)의 유기적 결합**: 접속 시점의 무결성 점검뿐만 아니라 접속 유지 중 백신 프로세스 강제 종료 시 실시간 즉시 격리
- **다계층 기기 프로파일링(Device Profiling)**: MAC OUI, DHCP 옵션, HTTP User-Agent, TCP 핑거프린팅을 분석하여 에이전트 설치가 불가능한 프린터/IP카메라 자동 식별
- **격리망 기반 무중단 자가 치료 (Self-Remediation)**: 보안 비준수 단말을 격리 VLAN으로 유도하여 백신 최신 패치 다운로드 웹페이지만 허용함으로써 자가 조치 지원

#### 한줄 요약
- 사전 무결성 점검, 사후 지속 감시, 기기 프로파일링, 동적 VLAN 격리 및 자가 치료를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **네트워크 접근 서버(NAS / Authenticator)**: 단말의 물리적 접속을 최초로 수용하는 L2/L3 스위치 또는 무선 AP로, RADIUS 프로토콜을 통해 정책 서버의 인가 결정을 실제 포트에 적용하는 집행점.

</details>

```text
[ 유/무선 접속 단말 (PC / 스마트폰 / IoT) ]
 ├─ NAC Agent (포스처 점검: OS 패치, 백신 상태)
 └─ 802.1X Supplicant / Web Browser
                    │
                    ▼ (1. 802.1X EAP / MAC Auth 요청)
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 접근 집행점 (NAS: L2/L3 Switch & Wireless Controller) ]               │
│  ├─ 802.1X Authenticator 포트 제어 (Authorized / Unauthorized)          │
│  └─ 동적 VLAN 변경 (VLAN Steering) 및 dACL 패킷 필터링 집행             │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (2. RADIUS Access-Request: 신원 + 단말 포스처 정보)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ NAC 정책 관리 서버 (Policy Server & AAA Engine) ]                     │
│  ├─ 사용자/단말 DB 인증 (Active Directory / LDAP / MDM)                 │
│  ├─ 포스처 엔진 (컴플라이언스 룰셋 판정: Pass / Fail)                     │
│  └─ 정책 결정 (Access-Accept: Return RADIUS VLAN Tag & dACL)            │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (3. 비준수 시 격리 VLAN 99 할당)
                                     ▼
                      [ 치료/업데이트 서버 (Remediation Server) ]
```

선의 의미: 단말의 접속 요청이 스위치(NAS)를 통해 NAC 정책 서버로 전달되어 포스처 평가를 거치고, 결과에 따라 정상 업무망(VLAN 10) 또는 격리 치료망(VLAN 99)이 스위치 포트에 동적 주입되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **엔드포인트 단말** | 802.1X 인증 정보 제시, 에이전트를 통한 레지스트리/프로세스 보안 상태 수집 | Supplicant |
| **접근 집행점 (NAS)** | 스위치 포트 차단/개방, RADIUS 응답에 따른 동적 VLAN 전환 및 dACL 적용 | Switch / AP |
| **NAC 정책 서버** | 신원 인증(AAA), 단말 프로파일링, 포스처 적합성 판정 및 접근 정책 하달 | Policy Server |
| **디렉터리/MDM 연동기**| Active Directory 계정 권한 및 EMM/MDM 단말 관리 상태(루팅/탈옥 여부) 질의 | External DB |
| **치료 서버 (Remediation)**| 격리된 비준수 단말에 OS 보안 패치 파일 및 백신 업데이트 엔진 다운로드 제공 | Patch Portal |

#### 한줄 요약
- 단말 서플리컨트, 스위치 NAS, NAC 정책 서버, 디렉터리 연동기, 치료 서버가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캡티브 포털(Captive Portal)**: 에이전트가 설치되지 않은 게스트나 신규 단말이 웹 브라우저 접속 시 강제로 인증 웹페이지로 리다이렉션하여 사용자 로그인 및 백신 설치를 유도하는 기술.

</details>

```text
1. 직원이 노트북을 사내 유선 랜 포트에 연결 ➔ 스위치 포트가 차단 상태에서 단말 MAC/802.1X 감지
            │
            ▼
2. NAC 에이전트가 단말 내 OS 패치 버전, 백신 실시간 감시 작동 여부를 수집하여 정책 서버로 전송
            │
            ▼
3. NAC 정책 서버가 AD 사용자 인증 및 컴플라이언스 룰셋 대조
            │
            ├─ [포스처 불합격: 백신 미구동] ➔ RADIUS 응답으로 'VLAN 99(격리망)' 및 치료 dACL 전송
            │     │
            │     ▼
            │   스위치가 포트를 격리망으로 이동 ➔ 백신 다운로드 페이지만 허용 ➔ 자가 치료 완료 후 재인증
            ▼
4. [포스처 합격: 전 항목 통과] ➔ RADIUS 응답으로 'VLAN 10(업무망)' 및 정규 접근 권한 전송
            │
            ▼
5. 스위치 포트 완전 개방 ➔ 정상 업무 수행 (사후 백신 종료 감지 시 즉시 1초 내 격리망으로 강등)
```

**동작 원리**

1. **링크 감지**: L2 스위치가 포트 업(Link Up)을 감지하고 기본 격리 상태 유지
2. **무결성 측정**: 단말 내부 에이전트가 백신 패턴 날짜, OS 빌드 번호, 필수 보안 SW 무결성 스캔
3. **정책 평가**: 기업 헌장(Security Baseline)과 단말 상태를 대조하여 허용/격리/차단 결정
4. **동적 권한 주입**: 스위치가 포트 태깅을 재프로그래밍하여 패킷을 해당 VLAN 브로드캐스트 도메인으로 분기
5. **지속적 감시**: 주기적 하트비트 폴링을 통해 단말의 실시간 위협 감지 시 즉시 포트 차단 실행

#### 한줄 요약
- 링크 연결, 포스처 무결성 수집, 정책 서버 판정, 동적 VLAN/dACL 할당, 사후 지속 감시 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **에이전트 기반 vs 에이전트리스 vs 802.1X 통제**: 구축 환경과 관리 단말 특성에 따른 NAC 구현 방식 비교.

</details>

| 비교 항목 | 에이전트 기반 NAC (Agent-based) | 에이전트리스 NAC (Agentless) | 표준 802.1X EAP 기반 NAC |
|:---|:---|:---|:---|
| **검증 깊이** | **매우 깊음 (프로세스, 레지스트리, 파일)**| 중간 (포트 스캔, 배너 그래빙) | **강력한 신원 인증 (인증서, ID/PW)**|
| **단말 지원 범위** | 사내 표준 PC(Windows, macOS) | **IP 전화기, 프린터, IoT 센서, 게스트**| 802.1X 지원 표준 단말 |
| **구축/배포 용이성**| 에이전트 사전 배포 부담 존재 | **매우 용이 (네트워크 장비 설정만 요구)**| 인증서 배포 및 인프라 설정 고도화 |
| **사후 지속 감시** | **완벽 지원 (백신 프로세스 종료 즉시 감지)**| 주기적 네트워크 폴링 스캔 한계 | 세션 유지 중심 (상태 변화 감지 제한)|
| **주요 적용 영역** | 임직원 핵심 업무용 노트북/PC | **스마트 빌딩 IoT 장치, 방문객 네트워크**| 전사 유무선 통일 엔터프라이즈 보안 |

#### 한줄 요약
- 임직원 PC는 심층 에이전트 기반, 비관리 IoT/게스트는 에이전트리스 및 802.1X를 하이브리드 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MAC 스푸핑(MAC Spoofing) 침투**: 공격자가 인가된 네트워크 프린터나 IP 카메라의 MAC 주소를 복제·위조하여 NAC의 단순 MAC 인증을 우회하고 사내망에 무단 침입하는 해킹 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인가된 IoT 기기(프린터)의 MAC 주소를 도용한 비인가 단말의 **MAC 스푸핑 우회 침투** | MAC 인증에 더하여 **다차원 DHCP/HTTP 핑거프린팅 프로파일링 및 802.1X MAB 연동** | MAC 위조 단말 100% 탐지 및 비인가 접속 원천 차단 |
| NAC 도입 초기 무지성 차단 정책 적용으로 인한 **대규모 정상 업무 마비 및 사용자 불만** | 단계적 구축: **모니터링(Audit Mode) $\rightarrow$ 경고/유예 $\rightarrow$ 완전 강제 차단** 적용 | 정책 오분류 예외 사전 정제 및 업무 연속성 완벽 보장 |
| NAC 정책 서버 및 RADIUS 인증 엔진 장애 시 전사 유무선 네트워크 **전면 통신 불통(All-Block)** | 스위치에 **RADIUS 서버 다운 시 이전 VLAN 유지(Critical VLAN / Fail-Open) 정책** 구성 | NAC 플랫폼 장애 시에도 가용성(Business Continuity) 100% 확보 |

#### 한줄 요약
- 다차원 프로파일링으로 MAC 스푸핑을 막고, 단계적 모드로 오차단을 방지하며, Fail-Open으로 가용성을 보장한다.

## Ⅶ. 결론

- 제로 트러스트(Zero Trust) 보안 모델의 제1원칙인 '신뢰하지 않고 항상 검증하라'를 엔드포인트 네트워크 계층에서 구현하기 위해 **NAC 아키텍처**는 전사 보안 거버넌스의 핵심 기반이며, 실무 구축 시 **에이전트와 에이전트리스의 하이브리드 프로파일링**, **동적 VLAN/dACL 기반 격리망 운영**, **EDR/SIEM/SOAR 솔루션과의 API 연동 폐루프 통제**를 구축하여 무결점 엔터프라이즈 접근 제어 환경을 완성

#### 한줄 요약
- 사전 포스처 검증과 동적 VLAN 격리 및 사후 지속 감시를 결합하여 제로 트러스트 네트워크 접근 제어를 구현한다.
