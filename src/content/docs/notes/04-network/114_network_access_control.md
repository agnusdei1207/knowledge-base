## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NAC (Network Access Control)**: 사용자 신원 인증과 단말의 보안 상태(포스처)를 검증하여 정상 단말만 업무망에 접속시키는 보안 체계.
- **Posture Assessment (포스처 점검)**: 단말의 OS 패치, 백신 실시간 감시, 디스크 암호화 여부 등을 스캔하여 사내 보안 규정 준수 여부를 평가하는 절차.

</details>

- 정의/개념: 신원·포스처에 따라 **접근·격리**를 집행하는 통제
- 배경/필요성: 경계 인증만으로는 일단 진입한 단말의 **상태 변화와 횡적 이동을 사후에 추적하는 비용**을 치르므로, 접속 시점에 포스처를 검증하고 결과에 따라 격리망을 부여하는 통제 지점을 스위치 포트 단계에 배치

#### 한줄 요약
- 사전 포스처 검증, 동적 격리망 할당, 사후 지속 모니터링을 통해 엔드포인트 무결성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Pre-Admission vs Post-Admission**: 네트워크 접속 전 단말의 보안 규정 준수를 검증하는 사전 통제와 접속 후 악성 행위 발생 시 즉각 격리하는 사후 통제.
- **Dynamic VLAN & dACL**: RADIUS 서버가 스위치 포트에 전달하는 파라미터에 따라 단말의 소속 VLAN과 L4 방화벽 ACL을 동적으로 변경하는 기술.

</details>

- 접속 전 **Pre-Admission 포스처** 검증
- 역할·상태별 **Dynamic VLAN·dACL** 할당
- 접속 후 **Post-Admission** 상태 변화 감시

#### 한줄 요약
- 사전 포스처 검증, 동적 VLAN/dACL 격리, 접속 후 지속적 감시를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NAS (Network Access Server)**: L2 스위치, 무선 AP 등 단말의 물리적 접속 지점에서 트래픽을 차단/개방하는 네트워크 장비.

</details>

```text
NAC
|-- Endpoint
|-- NAS
|-- Policy Server
|-- Directory and MDM
`-- Remediation Server
```

선의 의미: 단말의 접속 요청이 스위치를 통해 NAC 정책 서버로 전달되어 포스처 평가를 거치고 결과에 따라 정상 업무망 또는 격리 치료망이 스위치 포트에 주입되는 구조

| 구성요소 | 책임 |
|:---|:---|
| **Endpoint** | 인증 정보와 포스처 제공 |
| **NAS** | 포트·VLAN·dACL 정책 집행 |
| **Policy Server** | **AAA·포스처** 판정과 정책 하달 |
| **Directory and MDM** | 사용자·관리 상태 정보 제공 |
| **Remediation Server** | 격리 단말의 패치·백신 치료 |

#### 한줄 요약
- 정책 서버가 판정을 전담하고 스위치는 그 결과를 VLAN·dACL로 집행만 하므로, 정책 변경이 장비별 설정이 아니라 서버 한 곳에서 반영된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Quarantine VLAN (격리망)**: 포스처 점검에 불합격한 단말이 배치되는 네트워크로, 오직 사내 패치 서버 및 백신 다운로드 서버로의 접속만 허용됨.

</details>

```text
NAC 단말 감지, 포스처 평가, 동적 격리 및 치료 파이프라인
        │
       [물리 링크 감지]
        │
   1. [신원 및 포스처 수집]
        │
   2. [정책 적합성 판정]
        │
   +-------------------------------+
   | 적합: 3. 업무 VLAN·dACL 할당 |
   | 부적합: 3. 격리 VLAN·dACL 할당|
   +-------------------------------+
        │
   4. [접속 후 상태 감시]
```

- 1. 신원 및 포스처 수집
- 2. 정책 적합성 판정
- 3. 업무 또는 격리 VLAN·dACL 할당
- 4. 접속 후 상태 감시

#### 한줄 요약
- 포스처 판정에서 업무망 진입과 치료망 격리로 갈리며, 기준을 조일수록 침해 확산은 줄고 정상 단말의 업무 중단 위험은 커진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Agent-based** vs **Agentless** vs **802.1X EAP**.

</details>

| 비교 항목 | 에이전트 기반 NAC (Agent-based) | 에이전트리스 NAC (Agentless) | 표준 802.1X EAP 기반 NAC |
|:---|:---|:---|:---|
| 검증 깊이 | **프로세스·레지스트리** | 포트·배너 | 신원·자격 증명 |
| 지원 단말 | 관리 PC | 비관리 IoT·게스트 | 802.1X 지원 단말 |
| 배포 부담 | 에이전트 설치 | 네트워크 설정 | 인증서·AAA 설정 |
| 지속 감시 | 단말 내부 상태 | 주기적 네트워크 관찰 | 세션 인증 상태 |
| 주요 적용 | 관리 단말 포스처 | 비관리 단말 프로파일 | 유무선 포트 인증 |

#### 한줄 요약
- 임직원 PC는 심층 에이전트 기반, 비관리 IoT/게스트는 에이전트리스 및 802.1X를 하이브리드 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MAC Spoofing Bypass**: 공격자가 인가된 프린터의 MAC 주소를 복제하여 단순 MAC 기반 NAC 통제를 우회 침투하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **MAC 스푸핑** 기반 MAB 우회 | DHCP·HTTP 프로파일과 **802.1X** 병행 | 단순 MAC 신뢰 보완 |
| 초기 오차단으로 업무 중단 | **감사·유예·강제** 단계 적용 | 정책 예외 사전 정제 |
| RADIUS 장애로 접속 불가 | **Critical VLAN·Fail-Open** 정책 | 가용성과 보안 위험 균형 |
| 신규 위협의 정책 반영 지연 | **EDR·SIEM 격리 API** 연동 | 위협 기반 재평가 |

#### 한줄 요약
- 다차원 프로파일링으로 MAC 스푸핑을 막고, 단계적 모드로 오차단을 방지하며, Fail-Open으로 가용성을 보장한다.

## Ⅶ. 결론

- 관리 PC는 **에이전트 포스처**, IoT는 **프로파일링** 적용

#### 한줄 요약
- NAC는 사전 포스처 검증과 동적 VLAN 격리 및 사후 지속 감시를 결합하여 제로 트러스트 엔드포인트 접근 제어를 완성하는 필수 보안 인프라다.
