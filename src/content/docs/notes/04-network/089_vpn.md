## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 사설망(Virtual Private Network, VPN)**: 공용 인터넷 망(Public Internet) 상에서 암호화(Encryption), 인증(Authentication), 캡슐화(Encapsulation)를 적용한 논리적 가상 터널을 형성하여 지리적으로 분산된 사설망 간 또는 원격 사용자와 기업망 간의 안전한 통신을 제공하는 네트워크 기술.
- **분할 터널링(Split Tunneling)**: 사내 업무 트래픽(사설 IP 대역)만 VPN 터널로 라우팅하고 일반 인터넷 트래픽은 로컬 ISP 게이트웨이로 직접 분기하여 VPN 게이트웨이의 대역폭 부하를 절감하는 라우팅 기법.

</details>

- 정의/개념: L3 계층에서 패킷 전체를 캡슐화하는 **IPsec**, 웹 브라우저/TLS 기반의 **SSL VPN**, 초경량 최신 암호학 기반의 **WireGuard** 를 활용하여 공용망 상에 **기밀성, 무결성, 발신지 인증** 을 보장하는 사설 암호화 터널링 기술
- 배경/필요성: 물리 전용선(Leased Line) 구축의 막대한 비용 부담을 해소하고, 재택근무 및 클라우드(VPC) 확산 환경에서 엔드포인트와 기업 인프라 간의 안전한 원격 접속을 실현할 요구

#### 한줄 요약
- IPsec, SSL VPN, WireGuard를 통해 공용 인터넷 상에 암호화 터널을 수립하여 전용선 수준의 보안 통신을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **완전 순방향 비밀성(Perfect Forward Secrecy, PFS)**: Diffie-Hellman 키 교환을 매 세션마다 독립적으로 수행하여, 향후 마스터 장기 비밀키가 유출되더라도 과거에 기록된 암호화 세션 트래픽을 사후 복호화할 수 없도록 보장하는 암호학적 특성.
- **경로 MTU 블랙홀(PMTU Blackhole)**: VPN 헤더 추가로 인해 패킷 크기가 1500B를 초과할 때, DF(Don't Fragment) 플래그 설정 및 ICMP Type 3 Code 4 차단으로 인해 패킷이 조용히 드롭되어 연결이 정체되는 현상.

</details>

- **3대 보안 서비스 제공**: 대칭 암호(AES-GCM, ChaCha20) 기반 기밀성, HMAC/Poly1305 기반 무결성, 전자서명/PKI 기반 발신지 인증
- **계층별 적용 유연성**: Site-to-Site 백본 연동(L3 IPsec), 원격 사용자 웹 포털 접속(L7 SSL VPN), 저지연 모바일 연동(L3 WireGuard) 지원
- **동적 키 교환 및 재키잉(Rekeying)**: IKEv2 및 Noise 프로토콜 기반 자동 세션 키 협상 및 주기적 갱신을 통한 전방향 안전성(PFS) 보증

#### 한줄 요약
- 기밀성/무결성 보장, 계층별 터널링 유연성, PFS 기반 주기적 재키잉을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 연관(Security Association, SA)**: VPN 종단 간에 사용할 암호 알고리즘, 세션 키, 모드(Transport/Tunnel), 수명(Lifetime)을 명시한 단방향 논리적 연결 계약.
- **IKE(Internet Key Exchange)**: IPsec 터널 수립을 위해 양단 간에 안전한 인증 및 암호키 교환을 자동 협상하는 IETF 표준 프로토콜 (RFC 7296 IKEv2).

</details>

```text
[ VPN 클라이언트 / 지사 라우터 ] ──── (인터넷 공용망: 암호화 터널링) ────▶ [ VPN 게이트웨이 (방화벽) ]
 ├─ 원본 패킷 생성 (IP Head + Data)                                            ├─ 터널 헤더 검증 및 복호화
 ├─ 암호화 (ESP: AES-256-GCM)                                                  ├─ 접근 제어 정책(ACL/RBAC) 대조
 └─ 신규 터널 IP 헤더 부착 (Tunnel Mode)                                      └─ 내부 업무망으로 원본 패킷 포워딩
                                                                                        │
                                                                                        ▼
                                                                           [ 내부 사설 자원 (ERP / DB) ]
```

선의 의미: 원본 IP 패킷이 클라이언트에서 암호화 및 캡슐화되어 공용망을 통과한 후, 게이트웨이에서 복호화되어 내부망에 전달되는 파이프라인

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **VPN 게이트웨이** | 암호화 터널 종단, 패킷 캡슐화/역캡슐화, 복호화, 라우팅 및 접근 제어 집행 | Gateway Appliance |
| **IKE / 키 교환 모듈** | Diffie-Hellman 기반 키 교환, 상호 신원 인증 및 SA(보안 연관) 수명 관리 | UDP 포트 500/4500 |
| **ESP (Encapsulating Security Payload)**| IPsec에서 페이로드 암호화, 데이터 무결성 검증, 안티 리플레이 제공 | IP 프로토콜 50 |
| **분할 터널 라우터** | 사설 대역 목적지 패킷만 VPN 터널로 유도하고 공용 인터넷은 로컬 분기 | Routing Policy |

#### 한줄 요약
- VPN 게이트웨이, IKE 키 협상기, ESP 암호 모듈, 분할 터널 라우터가 결합하여 가상 사설망을 형성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IPsec 터널 모드(Tunnel Mode)**: 원본 IP 헤더를 포함한 전체 IP 패킷을 암호화하고 새로운 외부 IP 헤더(Outer IP Header)를 덧붙여 전송하는 모드로, 게이트웨이 대 게이트웨이(Site-to-Site) 통신에 표준으로 사용됨.

</details>

```text
1. VPN 클라이언트가 게이트웨이로 IKE_SA_INIT 메시지 전송 ➔ DH 파라미터 교환 및 암호화 채널 수립
            │
            ▼
2. IKE_AUTH 메시지를 통해 인증서(X.509) 또는 사전 공유 키(PSK) 기반 상호 신원 인증 수행
            │
            ▼
3. Child SA(IPsec ESP) 생성 완료 ➔ 양단 간에 대칭 암호화 키 및 SPI(Security Parameter Index) 바인딩
            │
            ▼
4. 송신단에서 원본 IP 패킷을 AES-256-GCM으로 암호화 후 신규 공용 IP 헤더를 씌워 터널로 송출
            │
            ▼
5. 수신 게이트웨이가 외부 헤더 제거, ESP 복호화 및 ICV 무결성 검증 ➔ 내부 업무 서버로 원본 패킷 전달
```

**동작 원리**

1. **1단계 IKE 협상**: IKEv2를 통해 양단 간의 보안 통신 채널(IKE SA) 수립
2. **2단계 인증 및 Child SA**: 사용자 자격 증명 검증 후 실제 데이터 전송용 ESP SA 파라미터 확정
3. **패킷 캡슐화**: 원본 패킷 전체를 ESP 페이로드로 감싸고 신규 Outer IP 헤더 추가
4. **암호화 전송**: 공용망 라우터들은 Outer IP만을 보고 라우팅하므로 원본 내용 완벽 은폐
5. **터널 해제**: 게이트웨이가 복호화 후 사설 라우팅 테이블(VRF)을 참조하여 백엔드로 포워딩

#### 한줄 요약
- IKE SA 수립, 상호 인증, Child SA 생성, ESP 캡슐화 전송, 게이트웨이 복호화 전달 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **IPsec vs SSL/TLS VPN vs WireGuard**: 정통 L3 망간 연동형, 웹/어플리케이션 원격 접속형, 모던 초경량 커널형 VPN의 비교.

</details>

| 비교 항목 | IPsec VPN (IETF RFC 4301) | SSL/TLS VPN (OpenVPN / AnyConnect) | WireGuard (Jason Donenfeld) |
|:---|:---|:---|:---|
| **동작 계층** | **L3 (네트워크 계층)** | **L4 ~ L7 (전송 및 응용 계층)** | **L3 (네트워크 계층, 커널 레벨)**|
| **암호화 스택** | IKEv2, AES-CBC/GCM, SHA-256 | TLS 1.3, OpenSSL 스택 | **Noise Protocol, ChaCha20-Poly1305**|
| **클라이언트 요구** | 전용 소프트웨어 또는 OS 내장 클라이언트 | **웹 브라우저 (무설치) 또는 에이전트** | 경량 에이전트 (코드 ~4,000라인) |
| **NAT 트래버설** | 복잡 (NAT-T: UDP 4500 캡슐화 필요) | **우수 (표준 HTTPS 포트 443 통과)** | **우수 (단일 UDP 포트 및 Roaming 지원)**|
| **주요 적용 영역** | **본사-지사, 클라우드 VPC 간 Site-to-Site**| **재택근무자 Client-to-Site 원격 접속** | **모바일 기기, K8s 클러스터 간 메시망**|

#### 한줄 요약
- IPsec은 본사-지사 백본망, SSL VPN은 재택근무 웹 접속, WireGuard는 고속 모바일 및 클라우드 연동에 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MSS 클램핑(MSS Clamping)**: TCP SYN 패킷의 MSS(Maximum Segment Size) 옵션 값을 라우터에서 강제로 축소(예: 1360B) 변경하여, VPN 암호화 오버헤드가 추가되더라도 전체 패킷이 MTU(1500B)를 초과하지 않도록 보정하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| VPN 암호화 헤더 추가로 인한 MTU 초과 시 패킷 단편화(Fragmentation) 및 드롭 발생 | VPN 게이트웨이에 **TCP MSS Clamping(1360~1400B) 및 PMTU Discovery** 적용 | 패킷 단편화 제거 및 대용량 파일 전송 처리율 40% 향상 |
| 재택 단말의 분할 터널링 허용 시 악성코드 감염 PC를 통한 내부망 침해 횡적 확산 | **엔드포인트 EDR/ZTNA 검증** 및 사내 접근 허용 서브넷 **최소 라우팅(Least Route)** 제한 | VPN 터널 경유 백도어 확산 차단 및 제로 트러스트 접근 제어 달성 |
| 장시간 동일 암호화 키 사용으로 인한 수학적 키 크래킹 및 세션 탈취 위험 | IPsec/WireGuard 상에서 **PFS(Perfect Forward Secrecy) 활성화 및 주기적 재키잉(Rekeying)** | 세션 키 주기적 갱신 및 과거 캡처 트래픽 사후 복호화 원천 차단 |

#### 한줄 요약
- MSS Clamping으로 MTU 병목을 제거하고, ZTNA 검증으로 분할 터널을 통제하며, PFS 재키잉으로 전방향 안전성을 확보한다.

## Ⅶ. 결론

- 분산 엔터프라이즈 환경에서 안전한 데이터 통신을 보장하기 위해 **Site-to-Site용 IPsec**, **재택 원격 접속용 SSL VPN**, **고성능 클라우드 연동용 WireGuard** 를 환경에 맞게 적재적소에 배치하되, 성능 저하와 보안 취약점을 방지하기 위해 **MSS Clamping 최적화**, **PFS 기반 주기적 재키잉**, **ZTNA(Zero Trust Network Access) 기반 연속 신원 검증**을 통합 구축하여 안전한 하이브리드 워크 인프라를 완성

#### 한줄 요약
- IPsec, SSL VPN, WireGuard를 목적별로 최적화하고 ZTNA 보안을 결합하여 고신뢰 VPN 인프라를 구축한다.
