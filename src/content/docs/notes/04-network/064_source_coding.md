## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소스 코딩 (Source Coding)**: 똑같은 글자나 픽셀이 반복되는 뻘짓(통계적 중복성)을 걷어내서, 원본 데이터 용량을 알뜰하게 다이어트시키는 압축 기술이다. (예: ZIP 파일, MP3 압축)
- **엔트로피 (Entropy)**: 정보이론의 아버지 섀넌이 정해놓은 "데이터를 무손실로 깎아낼 수 있는 절대 한계선"이다. 이 선 밑으로 깎으면 데이터가 부서져서 원복이 안 된다.

</details>

- 정의: **소스 코딩**은 데이터 내에 쓸데없이 반복되는 통계적 패턴을 찾아서 비트(Bit) 길이를 쫙 줄여버리는 데이터 압축 부호화 기술이다.
- 배경: 4K 영상이나 거대한 텍스트를 원본 그대로 통신망에 쏘면 대역폭이 터져나가고 서버 하드가 남아나질 않으니까, **전송/저장하기 전에 효율적으로 짜내서 용량부터 줄이려고 도입했다.**

#### 한줄 요약

- 쓸데없이 낭비되는 반복 데이터를 깎아내서 전송 용량을 줄이는 네트워크계의 다이어트 비법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가변 길이 부호 (VLC, Variable Length Coding)**: 자주 나오는 글자(예: 'a')는 1비트처럼 짧게, 어쩌다 나오는 글자(예: 'z')는 5비트처럼 길게 배정해서 전체 덩치를 아끼는 얍삽한 수법이다.
- **접두 부호 (Prefix Code)**: "내 코드가 남의 코드 앞부분이랑 똑같으면 안 된다"는 절대 룰이다. 이 룰이 없으면 압축 풀 때 띄어쓰기가 없어서 해석이 다 꼬여버린다.

</details>

- **확률 기반 가변 길이 할당**: 흔한 놈은 짧게, 희귀한 놈은 길게 배정해서 전체 트래픽 다이어트 효과를 극대화한다.
- **접두 부호 규칙 (디코딩 꼬임 방지)**: 띄어쓰기(구분자) 없이 비트가 줄줄이 들어와도, 접두 부호 룰 덕분에 수신자가 "아 여기서 끊어 읽는구나" 하고 실시간으로 칼같이 해석한다.
- **엔트로피 한계 도전**: 송수신자가 같은 '확률 통계표'를 들고, 섀넌의 엔트로피 한계점까지 비트를 영혼까지 쥐어짠다.

#### 한줄 요약

- 흔한 건 짧게, 희귀한 건 길게 배정하고(가변 길이), 수신자가 헷갈리지 않게 딱딱 끊어 읽도록(접두 부호) 설계하는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **코드북 (Codebook)**: "A는 01, B는 100"처럼 어떤 글자가 어떤 비트로 압축됐는지 적어놓은 족보다. 압축 파일 헤더에 꼭 넣어줘야 수신자가 풀 수 있다.
- **문맥 모델 (Context Model)**: 단순히 글자 개수만 세는 게 아니라, "q 다음엔 u가 자주 온다"는 눈치(문맥)까지 파악해서 압축률을 미친 듯이 끌어올리는 통계 모델이다.

</details>

```text
[ 소스 코딩 팩트 폭행 구조 ]

[ 1. 확률 모델 (통계청) ] ── (원본 스캔: A가 100번 나왔고 Z가 1번 나옴)
      │
      ▼
[ 2. 소스 부호기 (압축 공장) ] ── (오케이 A는 0, Z는 1111로 압축 쫙 돌림)
      │
      ▼ (코드북 족보랑 압축 데이터를 묶어서 발송)
[ 3. 소스 복호기 (해동 공장) ] ── (족보 보고 0은 A로, 1111은 Z로 줄줄이 풂)
      │
      ▼
[ 4. 무손실 원본 데이터 복원 ] ── (손실 없이 100% 똑같은 원본 등판 완료)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **확률 모델** | 원본 텍스트 쫙 훑어보고 **누가 자주 나오나 통계 내는 눈치코치** | Model |
| **소스 부호기** | 통계 보고 **자주 나오는 놈은 짧게 깎아서 압축 비트 찍어내는 공장** | Encoder |
| **코드북 (족보)** | 수신자가 압축 풀 때 **반드시 봐야 하는 이진 트리 변환 매핑 테이블** | Codebook |
| **소스 복호기** | 코드북(족보) 보고 **구분자 없이 들어오는 비트를 원본으로 쫙 푸는 놈** | Decoder |
| **CRC 검사기** | 압축 풀고 났더니 **비트 하나 삑사리 나서 다 깨진 거 아닌지 검사함** | Checker |

#### 한줄 요약

- 확률 재고(모델) $\to$ 짧게 압축하고(부호기) $\to$ 족보랑 같이 보내면 $\to$ 수신자가 족보 보고 원래대로 푼다(복호기).

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **재시작 지점 (Restart Marker)**: 가변 길이 코드는 중간에 1비트만 깨져도 그 뒤가 싹 다 밀려서 해석이 터지니까, "깨지면 여기서부터 다시 풀어라" 하고 중간중간 꽂아놓는 세이브 포인트다.

</details>

```text
[ 데이터 다이어트 및 원본 해동 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [심벌 빈도 통계 조사]     │
│ (통계청: 원문 스캔 완료. 'a'가 제일 흔함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [확률 모델 및 족보(트리) 완성]│
│ (부호기: 'a'에 1비트 할당. 매핑 족보 다 만듦)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [압축 비트 생성 및 발송]  │
│ (부호기: 데이터 쫙 압축해서 족보랑 같이 쏨)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [수신 측 족보 파싱 및 복호]│
│ (복호기: 족보 읽고 트리 타면서 비트 끊어 읽음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [100% 무손실 원본 복원]   │
│ (복호기: 압축 해동 완료. 원본이랑 토시 하나 안 틀림)
└──────────────────────────────┘
```

### 동작 원리

1. 통계 조사: 입력 데이터를 싹 스캔해서 뭐가 제일 많이 나오는지 확률 분포를 뽑아냄.
2. 족보 완성: 확률이 높은 심벌에는 짧은 비트열을 줘서 이진 부호 트리(코드북)를 완성함.
3. 데이터 압축: 원문을 비트로 바꾸면서 재시작 마커(세이브 포인트)와 CRC 찌꺼기 검사용 메타데이터를 넣음.
4. 발송 및 해동: 압축 파일 헤더에 있는 족보를 보고 수신자가 똑같이 트리를 타면서 해독함.
5. 무손실 복원: 단 1비트의 훼손 없이 100% 원본으로 복구 완료함.

#### 한줄 요약

- 통계 뽑고 $\to$ 족보 만들고 $\to$ 비트 짜내서 보내면 $\to$ 수신자가 족보 보고 풀어서 100% 살려내는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **허프만 부호화 (Huffman)**: 비트를 1개, 2개처럼 무조건 딱 떨어지는 '정수' 단위로만 쪼개서 트리를 만드는 가볍고 빠른 국민 압축 알고리즘이다. (ZIP, MP3에서 기본으로 씀)
- **산술 부호화 (Arithmetic)**: 비트를 소수점 단위(0.7비트 등)로 쪼개서 거대한 확률 구간에 구겨 넣는 수학 변태 알고리즘이다. 무겁지만 극한의 압축률을 뽑는다. (H.264 영상에 씀)

</details>

| 비교 항목 | **허프만 부호화 (Huffman)** | **산술 부호화 (Arithmetic)** |
|:---|:---|:---|
| 팩트 폭행 비유 | 빠르고 가볍게 압축하는 **가성비 국민 압축 (ZIP)** | 무겁지만 극한까지 쥐어짜는 **변태 압축 (H.264)** |
| 비트 할당 방식 | 딱 떨어지는 **정수 비트 (1비트, 2비트 등)** | 소수점까지 쪼개서 구겨 넣는 **확률 구간 분할** |
| 압축률 (엔트로피) | 정수로 쪼개다 보니 **극한의 압축은 쪼끔 안 됨** | 영혼까지 끌어모아 **엔트로피 한계에 거의 도달함** |
| 연산 난이도 | 족보(이진 트리)만 타면 돼서 **계산이 개빠름** | 더하기 곱하기 나누기 오지게 해서 **CPU 좀 타먹음** |
| 주요 활용 분야 | 텍스트 압축(ZIP), MP3, JPEG **기본 압축 계층** | 고화질 영상(H.264/HEVC), JPEG-2000 **고급 계층** |

#### 한줄 요약

- 싸고 빠른 텍스트나 음악엔 정수 단위 허프만을 쓰고, 극한으로 쥐어짜야 하는 4K 영상엔 산술 부호화를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **역압축 (Negative Compression)**: 압축 파일 만들 때 헤더에 넣는 족보(코드북) 용량이 원본 데이터보다 커져버려서, 압축했는데 오히려 용량이 뻥튀기되는 대참사다.
- **오류 전파 (Error Propagation)**: 가변 길이 코드라서 띄어쓰기가 없으니, 통신 중 앞부분 1비트만 날아가도 뒤가 싹 다 밀려서 파일 전체가 쓰레기가 되는 무서운 현상이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 압축했는데 **오히려 용량이 더 뻥튀기됨 (역압축)** | 원본 카톡 텍스트는 개짧은데, 압축 풀 때 쓰라고 넣은 족보(코드북 헤더) 용량이 더 커서 배보다 배꼽이 큼 | 짧은 데이터는 **압축 건너뛰거나, 통신 규격에 미리 약속된 글로벌 족보를 씀** | 바보 같은 헛수고(오버헤드) 컷트 및 낭비 방지 |
| 1비트 깨졌다고 **10GB짜리 영상 파일이 통째로 뻗음** | 가변 길이 코드라 1비트 밀리면 뒤에 있는 모든 코드가 도미노처럼 싹 다 박살 남 (오류 전파) | 일정 구간마다 리셋 포인트인 **'재시작 마커(Restart Marker)'를 박아둠** | 에러 나도 해당 구역만 버리고 나머지 구역은 정상 해동 |
| 산술 부호화 돌렸더니 **실시간 4K 영상 핑이 오지게 튐** | 확률 소수점 계산한다고 CPU가 나눗셈 연산을 수억 번 돌리느라 디코더 렉 걸림 | 산술 연산 복잡도 떨구고, 무조건 **하드웨어 전용 칩(디코더)에 연산 짬처리시킴** | 4K 실시간 스트리밍 버퍼링 컷트 및 쾌적한 시청 보장 |

#### 한줄 요약

- 배보다 배꼽 큰 역압축 막고, 파일 터질 거 대비해 세이브 포인트(마커) 박고, 빡센 계산은 하드웨어 가속기에 넘겨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 원천 데이터의 통계적 중복성을 제거하여 네트워크 대역폭과 스토리지 낭비를 박살 내기 위해, **가변 길이 접두 부호**를 앞세운 허프만과 산술 부호화 기반의 소스 코딩 기조 확립함

#### 한줄 요약

- 소스 코딩은 데이터 다이어트를 통해 네트워크 대역폭의 한계를 극복하고, 클라우드 저장 공간을 아껴주는 핵심 기술이다.
