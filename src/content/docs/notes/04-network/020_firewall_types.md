## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **방화벽(Firewall)**: 서로 다른 신뢰 수준을 가진 네트워크 세그먼트(내부망, 외부망, DMZ) 경계에서 사전 정의된 보안 정책(ACL)에 따라 비인가 접근을 차단하고 허가된 트래픽만 통과시키는 네트워크 보안 시스템.
- **접근 제어 목록(Access Control List, ACL)**: 출발지/목적지 IP, 포트 번호, 프로토콜 및 허용/차단(Allow/Deny) 액션으로 구성된 순차적 보안 규칙 집합.

</details>

- 정의/개념: 네트워크 경계에서 **기본 차단(Default Deny)** 원칙 하에 패킷 헤더 및 애플리케이션 페이로드를 검사하여 트래픽의 유입/유출을 통제하는 **경계 보안 시스템**
- 배경/필요성: 비인가 외부 호스트의 내부 자원 침입 방지, 악성 트래픽 확산 억제 및 규제 준수(컴플라이언스)를 위한 접근 제어 체계 확립 요구

#### 한줄 요약
- 기본 차단(Default Deny) 원칙에 따라 네트워크 경계에서 비인가 트래픽을 통제하는 보안 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 차단(Default Deny)**: 명시적으로 허용(Allow) 규칙에 부합하지 않는 모든 네트워크 트래픽을 최종적으로 자동 차단(Implicit Deny)하는 원칙.
- **상태 추적(Stateful Inspection)**: 송수신 패킷의 TCP 플래그, 시퀀스 번호 및 세션 상태 테이블을 유지하여 기존 연결의 정당한 응답 트래픽을 동적으로 허용하는 메커니즘.
- **심층 패킷 검사(Deep Packet Inspection, DPI)**: 전송 계층 헤더뿐만 아니라 애플리케이션 페이로드 내부를 검사하여 프로토콜 비정상성, 악성코드 및 시그니처를 식별하는 기술.

</details>

- **기본 차단(Default Deny)** 원칙을 통한 최소 권한(Least Privilege) 네트워크 정책 구현
- 세션 테이블 기반의 **상태 추적(Stateful Inspection)** 으로 아웃바운드 요청에 대한 인바운드 회신 트래픽 동적 허용
- 차세대 방화벽(NGFW)의 **심층 패킷 검사(DPI)** 를 통한 애플리케이션 식별, 사용자 인증 연동 및 침입 방지

#### 한줄 요약
- Default Deny와 상태 테이블 기반의 세션 추적 및 DPI 애플리케이션 제어를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 존(Security Zone)**: 동일한 신뢰 수준과 보안 정책이 적용되는 인터페이스 그룹(Trust, Untrust, DMZ).
- **상태 테이블(State Table)**: 현재 활성화된 세션의 5-튜플, TCP 상태(SYN_SENT, ESTABLISHED 등) 및 수명(Timeout)을 기록하는 메모리 테이블.

</details>

```text
[ 외부망 (Untrust Zone) ]
           │
           ▼
┌─────────────────────────────────────────┐
│              [ 방화벽 엔진 ]             │
│ 1. 보안 존 식별 (Untrust ➔ DMZ/Trust)    │
│ 2. 세션 상태 테이블 조회 (기존 세션 여부)  │
│ 3. 순차적 정책 규칙 평가 (ACL 매칭)      │
│ 4. DPI 위협 및 앱 검사 (NGFW 기능)       │
└────────────────────┬────────────────────┘
                     │ (정상 패킷 포워딩 및 세션 테이블 갱신)
                     ▼
      [ 내부망 (Trust) / DMZ 서버 ]
```

선의 의미: 보안 존 유입부터 세션 테이블 조회, ACL 룰 매칭 및 DPI 검사를 거쳐 인가된 영역으로 전달되는 구조

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **보안 존(Security Zone)** | 신뢰 수준별 네트워크 구획화 (내부망 Trust, 외부망 Untrust, DMZ) | 존 기반 정책 |
| **정책 규칙 베이스(ACL)** | 상단부터 순차적으로 평가되는 패킷 허용/차단/로그 규칙 집합 | 순차 매칭(Top-down) |
| **상태 테이블(State Table)** | 활성 세션의 5-튜플 및 TCP 연결 상태를 실시간 영속화하여 회신 트래픽 자동 통과 | 메모리 상주 |
| **DPI 위협 엔진** | 애플리케이션 제어, 안티바이러스, IPS, 취약점 공격 시그니처 실시간 스캔 | NGFW 엔진 |

#### 한줄 요약
- 보안 존 분리, 상태 테이블 세션 추적, 순차적 ACL 평가, DPI 엔진을 통해 트래픽을 검증한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **규칙 순차 평가(Top-Down Evaluation)**: 인입 패킷이 발생할 때 방화벽 룰셋의 1번부터 차례대로 매칭을 시도하여 최초로 일치하는 규칙의 액션을 즉시 실행하는 방식.

</details>

```text
1. 패킷 인입 및 인터페이스 보안 존(Zone) 확인
            │
            ▼
2. 상태 테이블(State Table) 조회: 기존 연결 세션 존재 여부 검사
            │
            ├─ [기존 세션 일치] ──▶ 4. 패킷 포워딩 및 세션 타이머 갱신
            └─ [신규 세션 인입]
                    │
                    ▼
3. 보안 규칙(ACL) 순차 매칭: Top-Down 방식으로 허용/차단 룰 검사
            │
            ├─ [차단(Deny) 룰 매칭] ────▶ 폐기(Drop) 및 로그 기록
            ├─ [기본 차단(Default Deny)] ─▶ 최종 차단(Drop)
            └─ [허용(Allow) 룰 매칭]
                    │
                    ▼
4. DPI 위협 검사(NGFW) ➔ 세션 테이블 신규 등록 후 정상 포워딩
```

**동작 원리**

1. **상태 테이블 선행 검사**: 인입 패킷이 기존 허용된 세션의 일부인지 확인하여 불필요한 ACL 룰 재평가 생략
2. **신규 연결 정책 검증**: 신규 SYN 패킷의 경우 보안 존 간 ACL 규칙을 상단부터 순차 매칭
3. **위협 및 앱 분석**: 허용 정책에 매칭된 패킷에 대해 DPI 엔진이 L7 애플리케이션과 유해 페이로드 여부 검증
4. **상태 테이블 등록**: 모든 검증을 통과한 신규 세션을 상태 테이블에 등록하고 패킷 전달
5. **회신 트래픽 처리**: 수신처로부터 돌아오는 응답 패킷은 상태 테이블 조회를 통해 자동 통과

#### 한줄 요약
- 상태 테이블 선행 조회 후 신규 연결에 대해 ACL 순차 평가와 DPI 검사를 수행하여 포워딩한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패킷 필터 방화벽(Packet Filtering)**: L3/L4 헤더(IP, Port)만을 독립적으로 검사하는 1세대 비상태형 방화벽.
- **상태 기반 방화벽(Stateful Inspection)**: TCP 세션 상태 머신을 추적하여 양방향 트래픽을 제어하는 2세대 표준 방화벽.
- **차세대 방화벽(Next-Generation Firewall, NGFW)**: 포트와 무관하게 애플리케이션을 식별하고 사용자 ID 연동 및 IPS/샌드박스를 통합한 3세대 방화벽.

</details>

| 비교 항목 | 1세대 패킷 필터링 | 2세대 상태 기반 (Stateful) | 3세대 차세대 방화벽 (NGFW) |
|:---|:---|:---|:---|
| **검사 계층** | L3 네트워크, L4 전송 계층 | L3, L4 (연결 문맥 포함) | **L3 ~ L7 전 계층 (심층 페이로드)** |
| **세션 상태 추적** | 미지원 (비상태형, Stateless) | **지원 (세션 상태 테이블 관리)** | 지원 (세션 + 앱 컨텍스트 추적) |
| **애플리케이션 제어** | 포트 번호 기반 단순 판별 | 포트 번호 기반 단순 판별 | **포트 비종속적 앱 식별(App-ID)** |
| **위협 차단 기능** | 단순 IP/Port 차단 | SYN Flood 등 세션 기반 방어 | **IPS, 안티바이러스, SSL 복호화 연동** |

#### 한줄 요약
- 단순 헤더 검사(1세대)에서 세션 상태 추적(2세대), L7 DPI 및 앱 식별 기반(NGFW)으로 발전했다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **규칙 섀도잉(Rule Shadowing)**: 상단의 광범위한 허용/차단 규칙으로 인해 하단의 세부적인 보안 규칙이 영원히 매칭되지 못하고 무효화되는 정책 오류.
- **DMZ(Demilitarized Zone)**: 외부 인터넷에 공개되는 서비스(웹, 메일, DNS)를 내부망과 격리하여 배치하는 중간 보안 구역.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공개 웹 서버 침해 시 내부 업무망 및 데이터베이스로의 횡적 이동 | **DMZ 보안 존 분리** 및 Zone 간 엄격한 단방향 정책 수립 | 웹 서버 침해 시에도 내부 업무망으로의 2차 침입(Pivot) 차단 |
| 상단 포괄적 규칙으로 인해 하단 세부 차단 룰이 무력화되는 **규칙 섀도잉** | 정책 최적화 분석 도구 활용 및 **구체적 규칙 상단 배치 원칙** 준수 | 정책 사각지대 및 의도치 않은 보안 홀 원천 방지 |
| HTTPS 암호화 트래픽 증가로 인한 L7 페이로드 위협 검사 불가 | NGFW의 **인바운드/아웃바운드 SSL/TLS 복호화(SSL Decryption)** 활성화 | 암호화된 악성코드 유입 탐지 및 프라이버시(금융/의료) 예외 설정 |

#### 한줄 요약
- DMZ 존 격리, 규칙 섀도잉 방지를 위한 룰 순서 정렬, SSL 복호화 적용으로 보안 사각지대를 해소한다.

## Ⅶ. 결론

- 엔터프라이즈 네트워크 경계 보안을 위해 **상태 기반 방화벽(Stateful)** 과 **차세대 방화벽(NGFW)** 을 계층적으로 결합하되, **Default Deny** 원칙과 **DMZ 분리**, SSL/TLS 복호화 검사 정책을 통합 수립하여 고도화된 침입 위협에 대응

#### 한줄 요약
- Default Deny 원칙과 NGFW 심층 패킷 검사를 결합하여 다계층 경계 보안을 확립한다.
