## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **방화벽**: 서로 다른 신뢰 구간 사이의 트래픽을 보안 규칙에 따라 허용하거나 차단하는 통제 장비이다.

</details>

- 정의/개념: **방화벽**은 서로 다른 신뢰 구간 사이의 트래픽을 보안 정책에 따라 허용하거나 차단한다.
- 배경/필요성: 통제되지 않은 경계는 비인가 접근과 공격 확산을 일으킨다.

#### 한줄 요약

- 방화벽은 출발지와 목적지뿐 아니라 연결 상태와 요청 내용까지 확인해 구간 사이 통행을 결정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 차단(Default Deny)**: 명시적으로 허용하지 않은 통신을 거부하는 정책이다.
- **상태 추적(Stateful Inspection)**: 연결 상태를 기록하여 요청과 응답의 연관성을 검사하는 기능이다.
- **심층 패킷 검사(Deep Packet Inspection, DPI)**: 페이로드의 응용 정보와 위협 패턴까지 분석하는 검사이다.

</details>

- **기본 차단**은 명시적으로 허용하지 않은 통신을 거부한다.
- **상태 추적**은 허용 연결의 응답인지 판별한다.
- **DPI**는 응용 정보와 위협 내용을 식별한다.

#### 한줄 요약

- 검사 정보가 많아질수록 응용별 통제는 정밀해지지만 정책과 처리 비용도 커진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 존(Security Zone)**: 정책 방향을 적용할 신뢰 구간이다.
- **접근 제어 목록(Access Control List, ACL)**: 순서에 따라 평가하는 허용•차단 규칙 목록이다.
- **상태 테이블(State Table)**: 허용한 연결의 양방향 상태를 저장한 표이다.
- **위협 엔진(Threat Engine)**: 응용 데이터에서 공격 패턴을 분석하는 기능이다.
- **정책 로그(Policy Log)**: 적용 규칙과 판정 결과를 기록한 데이터이다.

</details>

```text
규칙 집합
├── 보안 존
├── 상태 테이블
├── 위협 엔진
└── 정책 로그
```

선의 의미: 규칙 집합을 중심으로 정책 방향을 정하는 보안 존, 연결 문맥을 제공하는 상태 테이블, 응용 위협을 판별하는 위협 엔진과 판정 근거를 보존하는 정책 로그가 결합되는 정적 방화벽 통제 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 보안 존 | **보안 존**으로 출발•목적 구간•정책 방향 정의 |
| 규칙 집합 | **ACL**로 허용•차단 조건•평가 순서 규정 |
| 상태 테이블 | **상태 테이블**에 허용 연결의 양방향 튜플•상태 저장 |
| 위협 엔진 | **위협 엔진**으로 응용•공격 패턴 식별 |
| 정책 로그 | **정책 로그**에 적용 규칙•판정 결과 기록 |

#### 한줄 요약

- 외부•공개 서버•내부 구간을 나누고 규칙과 연결 상태와 위협 검사를 차례로 적용한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정책 판정(Policy Decision)**: 보안 존•연결 상태•첫 일치 규칙•위협 검사 결과를 결합해 허용 여부를 결정하는 과정이다.
- **보안 존 분류**: 입력•출력 인터페이스를 출발•목적 신뢰 구간에 대응시키는 절차이다.
- **상태 조회**: 인입 트래픽이 기존 허용 연결의 양방향 상태와 일치하는지 확인하는 절차이다.
- **규칙 평가**: ACL을 순서대로 검사하여 첫 일치 규칙의 허용•차단을 적용하는 절차이다.
- **위협 검사**: 허용 후보 트래픽의 응용 데이터와 공격 패턴을 분석하는 절차이다.

</details>

```text
인입 트래픽
     |
     v
1. 보안 존 분류
     |
     v
2. 상태 조회
     |
     v
3. 규칙 평가
     |
     +-- 명시 허용 없음 ---- 차단•로그
     |
     `-- 허용 규칙 일치
              |
              v
       4. 위협 검사
              |
              +-- 위협 탐지 ---- 차단•경보
              `-- 위협 없음 ---- 목적지 전달
```

### 동작 원리

**정책 판정**은 다음 네 검사 결과를 결합한다.

1. **보안 존 분류**: 입력•출력 인터페이스의 신뢰 구간을 결정한다.
2. **상태 조회**: 기존 허용 연결과의 연관성을 확인한다.
3. **규칙 평가**: 첫 일치 ACL의 허용•차단을 적용한다.
4. **위협 검사**: 응용 데이터와 공격 패턴을 분석한다.

#### 한줄 요약

- 구간과 연결 상태를 확인한 뒤 정책과 위협 검사를 통과한 트래픽만 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패킷 필터(Packet Filter)**: 주소와 포트 같은 패킷 필드로 통제하는 방화벽이다.
- **상태 기반 방화벽(Stateful Firewall)**: 연결 상태와 양방향 문맥으로 통제하는 방화벽이다.
- **차세대 방화벽(Next-Generation Firewall, NGFW)**: 응용•사용자•위협 정보로 통제하는 방화벽이다.

</details>

| 방화벽 방식 | **패킷 필터** | **상태 기반 방화벽** | **NGFW** |
|:---|:---|:---|:---|
| 적용 기준 | 단순•고속 주소•포트 통제 | 연결 요청•응답의 상태 통제 | 응용•사용자•위협별 통제 |
| 핵심 특징 | 패킷별 주소•포트 독립 검사 | 연결 테이블의 **상태 추적** | **DPI**의 응용•위협 내용 분석 |
| 한계 | 위조 출발지•연결 문맥 미식별 | 상태 테이블 자원 고갈 | 내용 검사 처리량 병목 |

> 요약: 패킷•연결•응용 문맥에 따라 방화벽을 선택한다.

#### 한줄 요약

- 패킷 필드는 명단을 보고 상태 기반은 연결 흐름을 보며 NGFW는 응용 내용까지 검사한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비무장 지대(Demilitarized Zone, DMZ)**: 공개 서버를 내부망과 분리한 경계 구간이다.
- **규칙 그림자(Rule Shadowing)**: 앞선 광범위 규칙 때문에 뒤 규칙이 적용되지 않는 현상이다.
- **복호화 예외**: 암호화 트래픽 검사 시 개인정보•법적 요구•성능을 고려해 검사하지 않을 범위를 정한 정책이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 광범위 허용 | 출발•목적•서비스 최소화 | 공격 표면 축소 |
| 공개 서버와 내부망 혼재 | **DMZ**로 공개 서버 분리 | 침해 확산 방지 |
| **규칙 그림자**로 뒤 규칙이 미적용 | 그림자•중복 규칙 자동 분석 | 정책 오판 방지 |
| 암호화 트래픽의 가시성 부족 | **복호화 예외** 기준 설정 | 위협 탐지와 준수 범위 조정 |
| 로그 과다•누락 | 중요 규칙별 **정책 로그** 보존•경보 차등 | 사고 추적성 확보 |

#### 한줄 요약

- 외부 사용자는 공개 웹 서버까지만 들어오게 하고 그 연결이 내부 서버로 직접 이어지지 않게 구간을 나눈다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **검사 범위 최소화(Minimum Inspection Scope)**: 필요한 주소•연결•응용 문맥까지만 검사해 통제 정밀도와 처리 비용을 균형화하는 원칙이다.

</details>

- **검사 범위 최소화** 원칙에 따라 연결 통제는 **상태 기반 방화벽**, 응용 위협 식별은 **NGFW**를 선택한다.

#### 한줄 요약

- 주소와 포트뿐 아니라 연결 상태와 필요한 응용 정보까지 검사 범위를 정해야 한다.
