## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **방화벽(Firewall)**: 아무나 못 들어오게 성벽을 치고, 살생부(ACL)에 허락된 놈만 문을 열어주는 가장 기본적이고 강력한 보안 통제 장비다.

</details>

- 정의: 서로 다른 신뢰 구간(외부망/내부망) 사이의 트래픽을 보안 규칙(Policy)에 따라 허용하거나 차단하는 **L3/L4/L7 통제 장비**
- 배경: 통제되지 않은 네트워크 경계는 해커의 비인가 접근과 악성코드 확산을 막을 수 없는 **무방비 상태를 초래하기 때문**

#### 한줄 요약

- 성벽(방화벽)을 세우고, 명단(ACL)에 없으면 다 쏴 죽이는 네트워크 보안의 제1 방어선이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 차단(Default Deny)**: "내가 허락한 거 빼고 전부 다 꺼져!" 하는 방화벽의 가장 절대적인 원칙이다.
- **상태 추적(Stateful Inspection)**: 한 번 나간 놈이 다시 들어올 땐 장부에 적어놨다가(상태 테이블) 묻지도 따지지도 않고 바로 문 열어주는 똑똑한 문지기 기능이다.
- **심층 패킷 검사(DPI)**: 택배 겉봉투(IP/Port)만 보는 게 아니라, 짐칸 내용물(Payload)까지 싹 다 뜯어보고 폭탄(위협) 들었는지 검사하는 빡센 검색대다.

</details>

- **기본 차단(Default Deny)** 원칙 하에, 명시적으로 룰(Rule)에 허용된 트래픽 외에는 전부 찢어버림.
- **상태 추적**으로 "내가 요청해서 들어오는 응답 트래픽인지" 문맥을 판별해 동적으로 포트를 열어줌.
- 요즘 세대(NGFW)는 **DPI**를 통해 겉면 주소뿐 아니라 안쪽 애플리케이션 데이터까지 샅샅이 식별함.

#### 한줄 요약

- 허락 안 한 건 기본적으로 찢어버리되(Deny), 내가 부른 놈은 살려주고(Stateful), 의심스러우면 짐칸까지 깐다(DPI).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 존(Security Zone)**: "여긴 믿을 놈(Trust), 저긴 밖(Untrust), 여긴 외부 공개용(DMZ)" 하고 땅따먹기로 구역을 쪼개놓은 거다.
- **접근 제어 목록(ACL)**: 위에서부터 아래로 "1번 통과, 2번 차단" 하면서 순서대로 매칭해보는 깐깐한 살생부 명단이다.
- **상태 테이블(State Table)**: "방금 192.168.1.1이 외부로 나갔음" 하고 현재 통신 중인 세션들을 실시간으로 칠판에 적어둔 장부다.
- **위협 엔진(Threat Engine)**: 데이터에 악성코드나 SQL 인젝션 패턴이 묻어있는지 귀신같이 잡아내는 스캐너다.

</details>

```text
[ 방화벽 팩트 폭행 통제 구조 ]

[ 외부망 (Untrust) ]
        │ (악성/일반 트래픽 짬뽕)
        ▼
┌───────────────────────────────┐
│          [ 방화벽 ]           │
│ 1. 보안 존 : 외부 -> 내부     │
│ 2. ACL 평가: 80번 포트 옴?    │
│ 3. DPI 검사: 내용물 이상 무?  │
│ 4. 상태 저장: 장부에 기록     │
└──────────────┬────────────────┘
               │ (깨끗한 트래픽만)
               ▼
[ 내부망 (Trust) / DMZ 서버 ]
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **보안 존 (Zone)** | 믿을 놈(Trust), 안 믿는 놈(Untrust), 반반(DMZ) **구역 쪼개기** | 신뢰도 기준 |
| **규칙 집합 (ACL)** | 허용할지 찢어버릴지 **위에서부터 순서대로 살생부 검사** | 정책(Policy) |
| **상태 테이블** | 나갔다 들어오는 놈은 프리패스 시켜주려고 **세션 장부에 기록** | 상태 추적 |
| **위협 엔진 (DPI)** | 짐칸 다 뜯어보고 **바이러스나 해킹 패턴 들었나 딥 스캔** | 차세대 기능 |

#### 한줄 요약

- 구역(Zone) 나누고, 살생부(ACL)로 거르고, 장부(State Table) 적고, 짐칸(DPI) 까본다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정책 판정(Policy Decision)**: 구역 확인, 상태 확인, ACL 검사, 내용물 검사를 싹 다 짬뽕해서 "얘는 살릴까 죽일까" 최종 결정하는 과정이다.
- **규칙 평가(Rule Evaluation)**: 방화벽 룰 1번부터 100번까지 줄 세워놓고, 조건 맞는 게 나올 때까지 위에서부터 무식하게 쭉 읽어 내려가는 짓이다.

</details>

```text
[ 방화벽 패킷 십자포화 차단 흐름 ]

┌──────────────────────────────┐
│ 1. [상태 조회] 장부 확인     │
│ (이미 허락받고 나갔던 놈인가?)│
└──────────────┬───────────────┘
               ├── (Yes) ──▶ (프리패스 통과!)
               ▼ (No: 처음 온 놈)
┌──────────────────────────────┐
│ 2. [규칙 평가] 살생부(ACL)   │
│ (1번 룰: 통과 / 2번 룰: 차단)│
└──────────────┬───────────────┘
               ├── (명시 안 됨) ──▶ (Default Deny로 찢어버림)
               ▼ (허용됨)
┌──────────────────────────────┐
│ 3. [위협 검사] 내용물 뜯기   │
│ (해킹 패턴 들어있나 딥스캔)  │
└──────────────┬───────────────┘
               ├── (해킹 발견) ──▶ (즉시 차단 및 경고 로그)
               ▼ (클린함)
┌──────────────────────────────┐
│ 4. [전달 및 장부 기록]       │
│ (상태 테이블에 적고 목적지로)│
└──────────────────────────────┘
```

### 동작 원리

1. 상태 조회: 기존 장부(상태 테이블)에 있는 허용된 연결인지 먼저 봄.
2. 규칙 평가: 첫 연결이면 위에서부터 순서대로 ACL 살생부 룰을 검사함.
3. 위협 검사: 룰은 통과했지만 혹시 나쁜 짓(해킹) 하는지 내용물(DPI) 분석.
4. 처리 및 기록: 싹 다 통과하면 통과시켜 주고 장부에 세션 기록을 남김.

#### 한줄 요약

- 장부 검사 $\to$ 룰 검사 $\to$ 내용물 검사 다 통과해야 비로소 들여보내 준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패킷 필터(Packet Filter)**: 1세대. 주소(IP)랑 포트만 보고 무지성으로 통과시키는 멍청한 옛날 방식이다.
- **상태 기반 방화벽(Stateful Firewall)**: 2세대. 누가 먼저 말 걸었는지 장부를 적어놔서, 안에서 밖으로 나갔다 들어오는 응답을 챙겨주는 방식이다. (현재 업계 기본)
- **NGFW(차세대 방화벽)**: 3세대. 80 포트로 속여서 들어와도 "너 토렌트 쓰네? 카톡 쓰네?" 하고 앱 단위로 귀신같이 알아채고 차단하는 요즘 끝판왕이다.

</details>

| 방화벽 방식 | **1세대 패킷 필터** | **2세대 상태 기반 (Stateful)** | **3세대 차세대 방화벽 (NGFW)** |
|:---|:---|:---|:---|
| 적용 기준 | 겉면에 적힌 **주소/포트**만 검사 | 요청-응답의 **문맥(Context)** 검사 | 포트 상관없이 **앱/유저** 검사 |
| 핵심 특징 | 패킷을 위에서부터 무식하게 비교 | **상태 테이블(장부)** 에 연결 내역 기록 | **DPI**로 짐칸 다 뜯어서 내용물 스캔 |
| 단점/한계 | 위조된 패킷(Spoofing)에 숭숭 뚫림 | 세션 장부 꽉 차면 메모리 뻗어버림 | 다 뜯어보느라 CPU 터지고 존나 느림 |

#### 한줄 요약

- 주소만 보는 건 1세대, 흐름을 보는 건 2세대, 앱 내용물까지 까보는 건 3세대(NGFW)다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DMZ(Demilitarized Zone)**: 웹서버를 내부망(직원 PC)이랑 섞어놓으면 털릴 때 다 털리니까, 중간 지대에 따로 격리해 놓은 방파제 동네다.
- **규칙 그림자(Rule Shadowing)**: 1번 룰에 "전부 허용" 써놓고 2번 룰에 "해커 차단" 써놓으면, 1번에서 룰 판정이 끝나버려 해커가 당당하게 걸어 들어오는 병크다.
- **복호화 예외(Decryption Exemption)**: 방화벽이 암호화 까보려다 임원진 금융 사이트 접속까지 까봐서 고소당하는 걸 막으려고 예외 처리해 두는 거다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공개용 웹서버 털렸더니 **사내 DB랑 직원 PC까지 다 털림** | 웹서버는 내부망과 분리된 **DMZ 구역**에 격리 배치 | 웹서버 털려도 내부망으로 2차 침해(Pivot) 차단 |
| 룰 잘못 짜서 **차단 룰이 무시당하고 다 뚫림** | 상단 룰에 다 먹히는 **규칙 그림자(Shadowing)** 분석 | 룰 순서 꼬여서 뻥 뚫리는 병크 방지 |
| NGFW가 개인 뱅킹 HTTPS까지 까봐서 **개인정보보호법 털림** | 금융, 의료 등 민감 카테고리는 **복호화 예외** 스킵 | 사생활 보호 및 복호화(CPU) 오버헤드 떡락 |
| 허용 안 한 트래픽 뚫고 들어오는데 **왜 뚫렸는지 모름** | 맨 마지막 `Default Deny` 룰에 **Drop 로그 켜기** | 쥐새끼(해킹 시도) 로그 확보 및 정책 구멍 추적 |

#### 한줄 요약

- 서버는 DMZ에 빼고, 룰 순서 꼬이지 않게 위에서부터 잘 짜고, 민감한 건 까보지 마라(복호화 예외).

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **검사 범위 최소화(Minimum Inspection Scope)**: 무지성으로 다 까보지 말고, 필요한 주소와 응용 문맥까지만 검사해야 방화벽 CPU가 안 터진다는 튜닝 원칙이다.

</details>

- **검사 범위 최소화** 원칙에 따라 기본 연결 통제는 **상태 기반(Stateful)** 룰을, 정밀 위협 식별은 **NGFW DPI**를 섞어 쓰는 하이브리드 아키텍처 기조 확립함

#### 한줄 요약

- 보안 빡세게 한다고 전부 다 L7(NGFW)으로 까보면 장비 뻗으니까, 적당히 섞어 쓰는 게 핵심이다.
