## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 슬라이싱(Network Slicing)**: 5G 망 하나를 식빵 썰듯이 가상으로 얇게 잘라서, 자율주행용 빵, 유튜브용 빵, 스마트 공장용 빵으로 완벽하게 나눠주는 마법이다.
- **SLA(Service Level Agreement)**: "자율주행 핑 1ms 넘어가면 우리가 배상금 낸다" 하고 통신사랑 기업이 목숨 걸고 맺는 품질 보장 계약서다.

</details>

- 정의: 단일 물리 5G 인프라를 가상화(NFV/SDN)해서 무선, 전송, 코어망 전체 구간을 **용도별(eMBB, URLLC, mMTC)로 완벽하게 찢어놓는 전용 가상망 기술**
- 배경: 옛날엔 트래픽 몰리면 다 같이 느려지는 '공용 도로'였지만, 자율주행이나 원격 수술은 단 1ms라도 지연되면 사람이 죽기 때문에 **절대 막히지 않는 '전용 차로'가 필요했기 때문**

#### 한줄 요약

- 5G망 1개를 소프트웨어로 칼같이 썰어서, 서로 절대 간섭하지 않는 100개의 가상 전용망으로 팔아먹는 5G의 핵심 밥줄이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **E2E 자원 조립(E2E Orchestration)**: 기지국(무선), 유선 랜선(전송망), 클라우드(코어망)라는 3가지 쌩판 다른 장비들을 하나로 묶어서 뻥 뚫린 1차선 도로로 조립하는 짓이다.
- **자원 격리(Resource Isolation)**: 옆 차선에서 콘서트 예매하느라 트래픽이 터져도, 내 차선(자율주행)은 0.001도 영향받지 않고 쌩쌩 달리는 철벽 방어력이다.

</details>

- **E2E 전 구간 통제**: 폰부터 기지국, 유선 백홀, 코어망 끝까지 싹 다 가상으로 엮어서 논리적인 슬라이스 1개를 통짜로 찍어냄.
- **칼 같은 자원 격리**: 논리망끼리 주파수, CPU, 대역폭을 물리적으로 아예 쪼개놔서 옆 동네 트래픽 폭주가 내 슬라이스로 절대 못 넘어옴.
- **동적 수명주기 관리**: 기업이 "내일 행사니까 대역폭 2배 늘려줘" 하면 소프트웨어로 딸깍해서 즉시 스케일 업(Scale-up)하고 행사 끝나면 흔적도 없이 부숴버림.

#### 한줄 요약

- 전 구간을 묶어서 썰어내고, 옆 동네 폭주를 철벽 방어하며, 필요할 때만 딸깍 찍어내는 가상 전용망이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **오케스트레이터(Orchestrator)**: "자율주행 차로 하나 만들어라" 명령 떨어지면, 밑에 장비들 쪼인트 까서 기지국, 전송망, 코어망 자원을 징발해 조립하는 슬라이스 총사령관이다.
- **NSSF(Network Slice Selection Function)**: 단말기가 접속하면 "너 유튜브냐 자율주행이냐?" 확인하고, 맞는 가상 차선(슬라이스)으로 강력히 끌고 가는 톨게이트 안내원이다.

</details>

```text
[ 5G 네트워크 슬라이싱 직관적 비교 구조 ]

[ 서비스 프로필 (계약서: 속도, 지연율) ]
               │
               ▼ (명령 하달)
[ 오케스트레이터 (총사령관: 차선 뚫어라!) ]
   ┌───────────┼───────────┐
   ▼           ▼           ▼
[ 기지국 ]  [ 전송망 ]  [ 코어망 ] (각자 자원 차출해서 1번 슬라이스 조립)
   │           │           │
   └───────────┼───────────┘
               ▼
[ NSSF (톨게이트: 자율주행은 1번 슬라이스로 타라) ]
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **SLA 프로필** | 속도는 얼마, 핑은 몇 ms 나와야 하는지 **목숨 걸고 적어놓은 B2B 계약 조건** | 템플릿 |
| **오케스트레이터** | 계약서 보고 기지국, 코어망 자원 뜯어와서 **가상 차로(슬라이스) 뚝딱 조립하는 총사령관** | CSMF/NSMF |
| **도메인 서브넷** | 무선망, 유선망, 코어망이 각각 뜯겨서 **슬라이스에 바쳐진 자원 조각들** | NSSMF |
| **NSSF** | 접속한 폰이 어떤 슬라이스(가상 차로)를 타야 할지 **번호표 뽑아주는 안내원** | 코어 NF |
| **AMF / UPF** | NSSF가 번호표 주면, 그 슬라이스 안에서만 굴러가는 **전용 문지기(AMF)와 패킷 라우팅 엔진(UPF)** | 5G Core |

#### 한줄 요약

- 오케스트레이터가 장비들 자원 뜯어와서 길을 뚫어놓으면, NSSF가 접속하는 놈들 식별 태그(S-NSSAI) 보고 제 길로 꽂아 넣는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **S-NSSAI**: "나는 eMBB 1번 슬라이스", "나는 URLLC 2번 슬라이스"라고 폰이랑 망이 서로 알아보는 슬라이스 고유 식별 번호표다.

</details>

```text
[ 5G E2E 슬라이스 생성 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [SLA 요구사항 접수]       │
│ (자율주행용 1ms 핑 뚫어줘)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [오케스트레이터 출동]     │
│ (기지국/코어망 자원 징발함)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [E2E 슬라이스 바인딩]     │
│ (징발한 자원으로 1차선 쫙 뚫음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [NSSF 정책 등록 (S-NSSAI)]│
│ (이 도로는 자율주행 전용이다)│
└──────────────┬───────────────┘
               ▼
   (자율주행 폰 접속 시 톨게이트 통과)
```

### 동작 원리

1. 요구사항 접수: 기업이 "안 끊기는 자율주행망 뚫어달라"고 SLA 요구.
2. 서브넷 자원 징발: 오케스트레이터가 무선 기지국, 유선 전송망, 가상 서버(UPF) 자원을 빼옴.
3. E2E 조립 및 검증: 빼온 자원 3개를 쭉 이어붙여서 통짜 E2E 슬라이스를 완성하고 핑 테스트함.
4. NSSF 라우팅 개통: "S-NSSAI 2번 달고 오는 놈은 이 슬라이스로 밀어 넣어라" 하고 NSSF에 등록함.

#### 한줄 요약

- 계약(SLA) 맺고, 자원 징발해서 하나로 묶고, 식별 태그(S-NSSAI) 등록해서 톨게이트 개방하는 프로세스다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **QoS(Quality of Service)**: 차선은 1개인데 구급차(우선순위 패킷) 오면 비켜주는 방식이다. 차가 꽉 막히면 결국 구급차도 같이 막히는 치명적 한계가 있다.

</details>

| 구분 | **기존 망 QoS (우선순위 제어)** | **5G 네트워크 슬라이싱** |
|:---|:---|:---|
| 핵심 특징 | **공용 도로**에서 구급차 오면 양보하며 비켜주기 | 구급차 전용 **고가도로를 아예 따로 건설하기** |
| 자원 격리 수준 | 논리적으로 우선순위만 매김 (트래픽 발생하면 다 같이 뒤짐) | 물리/논리 자원을 **아예 찢어놔서 완벽히 철벽 격리** |
| 적용 구간 | 특정 라우터나 스위치 구간 안에서만 잠깐 작동 | 스마트폰부터 코어망 끄트머리까지 **E2E 전 구간** |
| SLA 보장 능력 | 100% 핑 보장 못 함 (Best Effort) | 자원을 떼어놓고 예약했기 때문에 **100% 칼같이 보장** |
| 운용 복잡성 | 공유기 세팅하듯 간단함 | 전체 장비를 묶는 오케스트레이터(NSMF) 필수라 빡셈 |

#### 한줄 요약

- QoS가 꽉 막힌 도로 위에서 사이렌 울리며 달리는 거라면, 슬라이싱은 허공에 VIP 전용 고가도로를 새로 까는 거다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **PRB(Physical Resource Block)**: 기지국이 전파를 쏠 때 잘게 썰어놓은 주파수 덩어리. 이걸 슬라이스마다 칼같이 배분해야 격리가 된다.
- **Closed-loop 오케스트레이션**: 망이 뻗을 거 같으면 알아서 자원 늘리고, 널널하면 줄이는 짓을 사람이 개입 안 하고 AI가 알아서 무한 반복하는 자동 튜닝 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 무선 기지국에서 **유튜브 트래픽이 자율주행 핑 다 갉아먹음** | 코어망은 슬라이싱했는데 기지국 주파수(공기)가 짬뽕됨 | 무선 **PRB(주파수 자원)를 하드 파티셔닝** 기반 강제 찢음 | eMBB 폭주에도 URLLC 무선 핑 1ms 철통 방어 |
| 슬라이스 쪼개놨더니 **사용량 몰릴 때 혼자 뻗어버림** | 할당된 가상 자원을 초과했는데 스케일 업(확장)이 제때 안 됨 | **AI 기반 Closed-loop 오케스트레이션** 기반 선제적 자원 증설 | 트래픽 발생하기 전 SLA 위반 사전 컷 (Auto-scaling) |
| 공용 슬라이스 털린 해커가 **기업 비밀 슬라이스까지 기어 들어옴** | 논리적 격리를 뚫고 슬라이스 간 횡적 이동(Lateral Movement) 발생 | 슬라이스마다 **IPSec 터널링** 치고 인증 서버(UDM) 아예 찢어버림 | 슬라이스 간 해킹 전이 차단 및 완벽한 기밀성 |

#### 한줄 요약

- 코어망만 찢지 말고 기지국 주파수(PRB)까지 확실히 찢어야 하고, AI 오케스트레이터로 안 뻗게 알아서 자원 늘리게 튜닝해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- B2C 속도 경쟁을 넘어 B2B 맞춤형 과금 모델을 창출하기 위해선 **E2E 슬라이스 오케스트레이션** 및 **SLA 완벽 격리** 체계를 도입하는 5G 엔터프라이즈 아키텍처 기조 확립함

#### 한줄 요약

- 네트워크 슬라이싱은 통신사가 단순히 데이터 용량을 파는 장사치에서, '맞춤형 인프라'를 파는 B2B 플랫폼으로 진화하는 핵심 무기다.
