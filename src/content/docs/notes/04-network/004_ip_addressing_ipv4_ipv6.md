## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IP Addressing (IP 주소 체계)**: 인터넷 프로토콜 계층(L3)에서 단말 노드를 식별하고 패킷 라우팅을 수행하기 위해 부여하는 계층적 논리 주소.
- **IPv4 vs IPv6**: 32비트 기반 약 43억 개 주소 체계(IPv4)와 128비트 기반 $2^{128}$개 무한대 주소 체계(IPv6).

</details>

- 정의/개념: 인터넷 상의 모든 호스트를 식별하고 패킷 전달 경로를 결정하기 위한 **32비트(IPv4) 및 128비트(IPv6) 기반 계층적 논리 주소 체계**
- 배경/필요성: 모바일 기기, 클라우드 가상 인스턴스, IoT 사물인터넷의 폭발적 증가로 32비트 IPv4 공인 주소 공간(약 43억 개)이 전면 고갈되고, 임시방편인 NAT/PAT 도입으로 인한 종단 간 직접 통신(P2P/VoIP) 훼손 및 복잡한 가변 헤더로 인한 라우터 패킷 처리 오버헤드를 근본적으로 해결하기 위해, 128비트($2^{128}$)의 무한대 주소 공간, 40바이트 고정 헤더, 브로드캐스트를 배제한 애니캐스트/멀티캐스트 도입, SLAAC 무상태 자동 설정 및 IPsec 보안을 내재화한 IPv6 주소 체계를 도입하여 **글로벌 통신 연결성의 확장성과 고속 라우팅 하드웨어 최적화**를 달성할 필요

#### 한줄 요약
- 32비트 IPv4의 주소 고갈을 극복하고 128비트 IPv6를 통해 대규모 주소 공간과 고속 라우팅을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **LPM (Longest Prefix Match, 최장 프리픽스 일치)**: 라우팅 테이블 조회 시 목적지 IP 주소와 비트 일치 길이가 가장 긴 서브넷 경로를 우선 선택하는 알고리즘.
- **SLAAC (Stateless Address Autoconfiguration)**: IPv6에서 DHCP 서버 없이 라우터 광고(RA) 메시지만으로 호스트가 자체적으로 글로벌 IP를 자동 생성하는 기술.

</details>

- 네트워크 식별자와 호스트 식별자로 구분하는 **계층적 주소 구조(Hierarchical Addressing)**
- 라우팅 테이블에서 가장 구체적인 경로를 우선 선택하는 **최장 프리픽스 일치(LPM) 탐색**
- IPv6에서 라우터 광고(RA) 기반으로 즉시 주소를 구성하는 **무상태 자동 주소 설정(SLAAC)**

#### 한줄 요약
- 계층적 주소 지정, LPM 최적 라우팅, SLAAC 자동 설정을 통해 주소 관리 효율을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IPv4 헤더 (20~60바이트 가변)** vs **IPv6 헤더 (40바이트 고정)**: IPv6는 불필요한 필드를 제거하고 확장 헤더 체계로 전환하여 라우터의 하드웨어 패킷 처리 속도를 향상.

</details>

```text
[IP 주소 체계 아키텍처]
  │
  ├─ [IPv4 주소 체계 (32-bit)] (점-10진수 4옥텟)
  │     ├─ 네트워크 프리픽스 (서브넷 마스크 기반 망 식별)
  │     ├─ 호스트 식별자 (로컬 네트워크 내 단말 식별)
  │     └─ IPv4 가변 헤더 (20~60B, 체크섬 및 옵션 포함)
  │
  └─ [IPv6 주소 체계 (128-bit)] (콜론-16진수 8그룹)
        ├─ 글로벌 라우팅 프리픽스 (48비트 계층적 집약)
        ├─ 서브넷 식별자 (16비트 서브넷 구성)
        ├─ 인터페이스 식별자 (64비트 EUI-64/랜덤 단말 식별)
        └─ IPv6 고정 헤더 (40B 고정 헤더 + 확장 헤더 체인)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| IPv4 주소 | 32비트 주소와 CIDR 프리픽스 제공 및 가변 헤더 포워딩 |
| IPv6 주소 | 128비트 주소와 프리픽스 제공 및 대규모 주소 공간 보장 |
| IPv6 고정 헤더 | 40바이트 고정 헤더를 통한 라우터 하드웨어 고속 처리 |
| 확장 헤더 | 옵션·라우팅·단편화 기능을 체인 형태로 연결 처리 |

#### 한줄 요약
- IPv6는 헤더를 40바이트로 고정하고 옵션을 확장 헤더 사슬로 밀어내, 라우터가 패킷마다 가변 헤더 길이를 해석하던 비용을 없애 하드웨어 고속 포워딩을 얻는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **L3 포워딩 5단계**: 패킷 수신 $\to$ 라우팅 테이블 LPM 대조 $\to$ 넥스트홉 결정 $\to$ L2 MAC 주소 해석(ARP/NDP) $\to$ 프레임 전송.

</details>

```text
[IP 패킷 수신]
      |
1. 경로 조회
      |
2. LPM 선정
      |
3. 넥스트홉 결정
   /       \
 IPv4     IPv6
  |         |
4. ARP    4. NDP
   \       /
   [프레임 송출]
```

- 1. 경로 조회: 목적지 프리픽스와 경로 대조
- 2. LPM 선정: 가장 구체적인 프리픽스 선택
- 3. 넥스트홉 결정: 출력 인터페이스 확인
- 4. ARP/NDP: 넥스트홉의 링크 주소 해석

#### 한줄 요약
- 넥스트홉 결정까지는 IPv4와 IPv6가 같은 LPM 조회 비용을 치르고, 링크 주소 해석 단계에서만 ARP와 NDP로 갈려 해석에 드는 링크 부담이 달라진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Anycast (애니캐스트)**: 동일한 IP 주소를 여러 노드에 부여하고, 라우팅 상 가장 가까운(Topologically Nearest) 단일 노드로 트래픽을 전달하는 전송 방식.

</details>

| 비교 항목 | IPv4 주소 체계 | IPv6 주소 체계 |
|:---|:---|:---|
| 주소 길이 및 공간 | 32비트 주소 공간 | 128비트 주소 공간 |
| 통신 방식 | 유니·브로드·멀티캐스트 | 유니·멀티·**애니캐스트** |
| 헤더 구조 | 20~60바이트 가변 헤더 | 40바이트 기본 헤더와 확장 헤더 |
| 주소 자동 설정 | 수동 설정·DHCP | SLAAC·DHCPv6 |
| IPsec 지원 | 구현 가능 | 구현 가능 |
| 단편화 책임 | 호스트와 중간 라우터 | 출발지 호스트 |

#### 한줄 요약
- IPv6는 브로드캐스트를 없애고 단편화를 출발지에 몰아 라우터의 홉당 비용을 줄이는 대신, 주소 설정과 이웃 탐색을 호스트 쪽 멀티캐스트 절차로 옮긴 구조다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Dual-Stack (듀얼 스택)**: 네트워크 장비와 서버에 IPv4와 IPv6 프로토콜 스택을 동시에 구성하여 두 프로토콜을 병행 처리하는 표준 전환 기술.
- **NAT64 / DNS64**: IPv6 전용 클라이언트가 IPv4 전용 서버와 통신할 수 있도록 DNS 쿼리를 변환하고 패킷 주소를 상호 매핑하는 전환 기술.
- **RA Guard (Router Advertisement Guard, RFC 6105)**: L2 스위치가 액세스 포트로 들어오는 ICMPv6 라우터 광고를 검사해 신뢰 포트가 아닌 곳에서 온 RA를 폐기함으로써 위조 라우터가 기본 경로를 가로채는 것을 막는 기능.
- **프라이버시 확장 (Privacy Extensions, RFC 4941)**: SLAAC의 인터페이스 ID를 MAC 기반 EUI-64 대신 난수로 생성하고 주기적으로 교체한 임시 주소로 통신해, 주소로 단말을 장기간 추적하는 것을 막는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| IPv4 전용 보안 정책만 적용 시 IPv6 터널링을 통한 백도어 침해 | 모든 방화벽/IPS에 IPv6 보안 룰셋을 IPv4와 동시 적용 | IPv6 비인가 트래픽 침해 차단 |
| 공격자의 위조 라우터 광고(RA)로 인한 트래픽 가로채기(스푸핑) | L2 스위치 포트에 **RA Guard** 활성화 | 비인가 라우터 위조 공격 방어 |
| SLAAC 사용 시 MAC 주소 노출(EUI-64)로 인한 사생활 추적 위험 | 인터페이스 ID를 주기적으로 무작위 생성하는 **프라이버시 확장** 적용 | 호스트 MAC 은닉 및 추적 방지 |
| IPv6 망과 IPv4 레거시 망 간의 상호 통신 불가 문제 | **Dual-Stack** 우선 적용, 불가 구간은 **NAT64 / DNS64** 변환 | 점진적 무중단 IPv6 전환 달성 |

#### 한줄 요약
- IPv6는 SLAAC·RA처럼 호스트가 스스로 설정하는 편의를 얻는 대신 위조 RA·주소 추적이라는 새 공격면을 열므로, 전환기에는 IPv4 정책을 복제하는 것보다 IPv6 고유 제어(RA Guard·임시 주소)를 먼저 세우는 편이 싸다.

## Ⅶ. 결론

- 글로벌 통신사 5G/6G 모바일 코어와 하이퍼스케일 클라우드 데이터센터의 표준 주소 인프라로 자리잡았으며, 실무 전환 시에는 **장비별 Dual-Stack(듀얼 스택) 구성, IPv6-IPv4 이기종 망 간 통신을 위한 NAT64/DNS64 및 6in4 터널링 적용, L2 스위치 상의 RA Guard 활성화 및 EUI-64 MAC 노출을 방어하는 RFC 4941 프라이버시 확장**을 결합하여 레거시 서비스의 단절 없는 안정적인 차세대 IP 주소 전환을 완성

#### 한줄 요약
- IP 주소 체계는 IPv4의 한계를 극복하고 128비트 주소 공간, 고정 헤더, 보안이 내재화된 IPv6로 진화하여 대규모 인터넷을 지탱하는 핵심 통신 기술이다.
