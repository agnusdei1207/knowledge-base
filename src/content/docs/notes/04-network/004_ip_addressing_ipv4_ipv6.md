## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IP 주소(IP Address)**: 택배 아저씨(라우터)가 집(호스트)을 찾아갈 수 있게 도로명 주소처럼 부여한 논리적 식별 번호이다.
- **IPv4**: "192.168.0.1"처럼 32비트(약 43억 개)로 이루어진 친숙한 옛날 주소로, 지금은 고갈돼서 씨가 마른 구식 프로토콜이다.
- **IPv6**: 주소가 모자라서 128비트로 확 늘린 차세대 주소로, 전 지구의 모래알마다 IP를 줄 수 있을 만큼 어마어마한 크기를 자랑한다.

</details>

- 정의: 호스트를 식별하고 패킷이 목적지를 찾아가는(라우팅) 길잡이 역할을 하는 **논리 주소 체계**
- 배경: 스마트폰, IoT 기기가 폭발하면서 기존 32비트 IPv4로는 **IP 주소가 동나버리는 고갈 사태** 터졌기 때문

#### 한줄 요약

- 주소가 부족해서 다 같이 나눠 쓰는 낡은 IPv4와, 무한대로 뿌려주는 신식 IPv6 체계다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최장 프리픽스 일치(LPM, Longest Prefix Match)**: 라우터가 길을 찾을 때, 여러 경로 중 목적지 주소와 가장 길게 똑같이 일치하는(가장 구체적인) 경로로 짐을 던져주는 룰이다.
- **SLAAC(Stateless Address Autoconfiguration)**: IPv6 환경에서 DHCP 서버 없이, 공유기(라우터)가 뿌리는 정보만 듣고 PC가 알아서 자기 IP를 세팅하는 무상태 자동 할당 기술이다.

</details>

- 계층적 비트 구조를 활용하여 여러 대역을 묶어버리는 라우팅 경로 요약(Route Aggregation) 지원.
- 목적지 IP를 대조할 때 **최장 프리픽스 일치(LPM)** 를 기준으로 가장 좁고 정확한 경로 선별.
- IPv6 환경에서는 공유기만 꽂으면 기계가 알아서 주소를 만드는 **SLAAC(무상태 주소 자동 설정)** 지원.

#### 한줄 요약

- LPM으로 가장 정확한 길을 찾고, IPv6는 서버 없이도 알아서 주소(SLAAC)를 만든다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **네트워크 프리픽스(Network Prefix)**: IP 주소의 앞부분으로, "이 컴퓨터는 서울시 강남구에 있음"을 나타내는 동네(서브넷) 식별자이다.
- **인터페이스 식별자(Interface Identifier)**: IP 주소의 뒷부분으로, 강남구 안의 "101동 202호"처럼 단일 기기(호스트)를 식별하는 번호이다.

</details>

```text
[ IP 주소 계층적 직관적 비교 구조 ]

[ IPv4 구조 (32비트) ]
┌──────────────────────────┬──────────────────────────┐
│ 네트워크 프리픽스 (동네) │ 호스트 식별자 (아파트)   │
└──────────────────────────┴──────────────────────────┘

[ IPv6 구조 (128비트) ]
┌──────────────────────────┬──────────────────────────┐
│ 글로벌 라우팅 & 서브넷   │ 인터페이스 식별자 (MAC)  │
└──────────────────────────┴──────────────────────────┘
```

| 구성 요약 | **IPv4 (구식 번호판)** | **IPv6 (신식 번호판)** |
|:---|:---|:---|
| 주소 길이 및 표기 | **32비트**, 10진수 4칸 (`192.168.0.1`) | **128비트**, 16진수 8칸 (`fe80::1ff:fe23:4567`) |
| 주소 구분 방식 | 클래스(A~C) 쓰다가 **CIDR(/24)** 도입 | **네트워크 프리픽스(64비트)** + **인터페이스 식별자(64비트)** |
| 통신 방식 | 유니(1:1), 브로드(1:전체), 멀티(1:N) | 시끄러운 브로드캐스트 버리고 **애니캐스트(1:가까운놈)** 추가 |
| 헤더 구조 | 20~60바이트 (옵션 껴서 **가변적이라 느림**) | 40바이트로 **고정(군더더기 싹 다 빼서 라우팅 빠름)** |

#### 한줄 요약

- 주소를 앞뒤로 쪼개서 앞은 동네(네트워크)를 찾고 뒤는 아파트(호스트)를 찾는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ARP (주소 결정 프로토콜)**: IPv4에서 "IP는 아는데 댁들 중에 192.168.0.5 누구요?" 하고 동네방네 브로드캐스트를 때려서 물리적인 MAC 주소를 알아내는 촌스러운 방식이다.
- **NDP (이웃 탐색 프로토콜)**: IPv6에서 시끄러운 ARP를 버리고, ICMPv6 멀티캐스트를 써서 우아하게 주변 MAC 주소를 찾아내는 스마트한 방식이다.

</details>

```text
[ 패킷 라우팅 및 주소 해석 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 목적지 IP 달린 패킷 도착  │
│ (길 찾아 주세요!)            │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 라우팅 테이블 대조        │
│ (서브넷 마스크랑 비트 AND 연산)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 넥스트 홉 결정 (LPM)      │
│ (가장 길게 일치하는 문으로 던짐)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 링크 MAC 주소 해석        │
│ (IPv4는 ARP, IPv6는 NDP 쏨)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. L2 프레임 포장 및 전송    │
│ (MAC 헤더 붙여서 랜선으로 발사)│
└──────────────────────────────┘
```

### 동작 원리

1. 패킷 도달: 라우터에 IP가 달린 짐이 도착함.
2. 테이블 대조: 목적지 IP를 라우팅 테이블과 비트 AND 연산해서 경로를 맞춰봄.
3. 넥스트 홉 결정: 여러 경로가 겹치면 일치하는 숫자가 가장 많은(LPM) 최적의 출구를 고름.
4. 주소 해석: 출구로 나가기 위해 바로 옆 장비의 MAC 주소를 ARP(IPv4)나 NDP(IPv6)로 알아냄.
5. 프레임 전송: 알아낸 MAC 주소로 겉포장을 다시 해서 옆 라우터로 쏴버림.

#### 한줄 요약

- LPM으로 최적의 문을 고르고, ARP나 NDP로 상대방 MAC 주소를 따서 넘겨주는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **네트워크 주소 변환(NAT, Network Address Translation)**: 공유기 하나에 공인 IP 하나만 꽂고, 집 안의 폰/패드/PC는 가짜 주소(사설 IP)를 노나 써서 IPv4 고갈을 버티는 눈물겨운 꼼수이다.

</details>

| 구분 | **IPv4 주소 체계** | **IPv6 주소 체계** |
|:---|:---|:---|
| 주소 고갈 꼼수 | **공유기(NAT), 서브네팅(CIDR)** 으로 강력히 버팀 | **무한대 주소 공간** 기반 꼼수 없이 1기기 1공인 IP 할당 |
| IP 자동 할당 | DHCP 서버 터지면 IP 못 받아서 통신 끊김 | 서버 없이 라우터가 뿌리는 **SLAAC(무상태)** 로 알아서 세팅 |
| 보안(IPsec) | 쓸 순 있는데 덕지덕지 **옵션** 붙여야 함 | 묻지도 따지지도 않고 **표준 스펙에 기본 내장됨** |
| 패킷 단편화 | 중간 라우터가 짐 무거우면 **쪼개느라 CPU 낭비함** | 송신자가 알아서 쪼개서 보냄 (중간 라우터는 걍 쏨) |

#### 한줄 요약

- IPv4는 모자란 주소를 공유기(NAT)로 돌려막고, IPv6는 공간이 썩어 넘쳐서 그딴 거 안 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **듀얼 스택(Dual Stack)**: 당장 내일 IPv4를 다 갖다 버릴 순 없으니까, 장비 하나에 IPv4와 IPv6 스택을 둘 다 올려서 투잡을 뛰게 만드는 과도기 기술이다.
- **라우터 광고(RA, Router Advertisement)**: 공유기가 주기적으로 "내 네트워크 대역은 이거고 게이트웨이는 나야!" 하고 방송해서, 듣는 PC들이 알아서 IP를 만들게(SLAAC) 해주는 메시지이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| IPv4 방화벽만 막아뒀다가 IPv6 터널링으로 해커가 뚫음 | 전 장비 대상 **IPv4/IPv6 듀얼 스택 보안 정책 동시 적용** | 차세대 주소를 악용한 백도어 해킹 차단 |
| 불량 장비가 **위조된 라우터 광고(RA)** 뿌려서 트래픽 납치함 | L2 스위치에 가짜 RA 차단하는 **RA Guard** 설정 활성화 | 엉뚱한 게이트웨이로 가는 스푸핑 방지 |
| IPv6(SLAAC)는 주소가 수시로 바뀌어서 범죄자(IP) 추적이 안 됨 | IP를 강제로 기록해서 뿌려주는 **DHCPv6** 병행 도입 | 기업 망 IP 이력 관리 및 투명성 확보 |

#### 한줄 요약

- 두 개 다 열어놓고(듀얼 스택) 감시하고, 해커가 가짜 라우터 행세하는 것(RA 스푸핑)을 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **IPv6 전환 기술(IPv6 Transition Mechanism)**: 구식 아파트(v4)에서 신식 아파트(v6)로 가기 위해, 양쪽을 다 쓰는 듀얼 스택, v6를 v4로 싸서 보내는 터널링, 아예 번역해 주는 주소 변환(NAT64) 등을 쓰는 전략이다.

</details>

- **IPv6 전환 기술** 원칙에 따라, 장비가 지원하면 **듀얼 스택** 기반 올리고, v4 전용망과 통신할 땐 **NAT64 변환** 기반 호환성을 보장하는 기조 확립함

#### 한줄 요약

- 세상이 한방에 바뀌진 않으니, 듀얼 스택과 주소 변환(NAT64)으로 천천히 갈아타는 게 정답이다.
