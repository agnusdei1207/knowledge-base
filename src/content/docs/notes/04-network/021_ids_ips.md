## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **침입 탐지 시스템(IDS)**: 지나가는 트래픽을 몰래 복사해서 떠보고 "어? 저놈 해커다!" 하고 사이렌(경보)만 울리는 CCTV 같은 장비다.
- **침입 방지 시스템(IPS)**: 아예 길목 한가운데 서서 "어? 해커네?" 하면 강력히 바로 연결을 끊어버리는 실전 경호원 장비다.

</details>

- 정의: **IDS** 기반 침입을 탐지해 경보만 울리고, **IPS** 기반 길목(인라인)에서 악성 트래픽을 실시간 차단하는 **보안 시스템**
- 배경: 방화벽이 정상적으로 열어준 포트(예: 80번 웹)를 타고 들어오는 딥한 취약점 공격은 **방화벽만으로는 잡을 수 없었기 때문** #### 한줄 요약

- 도둑 들어왔을 때 쳐다보고 소리만 지르면 IDS고, 빠따 들고 직접 때려잡으면 IPS다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시그니처 탐지(Signature Detection)**: 해커들 지명수배 전단지(DB)랑 얼굴 대조해보고 "너 저번에 털었던 그놈이네!" 하고 잡는 오용 탐지 방식이다. (정확하지만 신종에 취약)
- **이상 탐지(Anomaly Detection)**: 평소 10메가 쓰던 놈이 갑자기 10기가를 쓰면 "너 뭔가 이상해" 하고 묶어버리는 AI 기반 통계 탐지다. (신종 잡지만 오탐 심함)

</details>

- **IDS** 기반 경로 밖에서 트래픽을 복제(Mirror)해 분석하므로 통신 지연이 없으나, **IPS** 기반 인라인(Inline)에서 분석하므로 통과 못 하면 뻗어버림.
- **시그니처 탐지**(전단지 대조)와 **이상 탐지**(평소와 다른 짓) 기법을 섞어 얄미운 제로데이(0-Day) 공격까지 방어.

#### 한줄 요약

- 지명수배지(시그니처)로 익숙한 도둑을 잡고, 평소랑 다른 짓(이상 탐지)으로 처음 보는 도둑을 잡는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세션 정규화(Session Normalization)**: 해커가 백신 안 걸리려고 패킷을 갈기갈기 찢거나 암호화해서 던진 걸 원래대로 깔끔하게 복원하는 작업이다.
- **세션 복원(Session Reconstruction)**: 조각난 패킷들을 양방향 통신 흐름에 맞게 레고 조립하듯 합쳐서 제대로 된 문맥을 파악하는 기술이다.

</details>

```text
[ 직관적 비교 기반 IDS/IPS 구조 ]

[ 네트워크 트래픽 유입 ]
           │
           ▼
[ 수집기 / 세션 정규화기 ] ── (해커가 찢어 보낸 패킷 조립 및 쌩얼 복원)
           │
           ▼
    [ 탐지 엔진 ] ── (전단지(시그니처) 대조 & 평소랑 다른지(이상 탐지) 스캔)
           │
           ▼
    [ 정책 엔진 ] ── ("오탐 아니지? 99% 해커 맞지?")
           │
           ▼
    [ 대응 장치 ] ──▶ [ IDS 모드 ] : 사이렌만 웽웽 울리고 냅둠
                 ──▶ [ IPS 모드 ] : 즉시 연결 끊고 포트 차단해버림!
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **수집 및 정규화기** | 해커가 꼬아놓은 패킷을 원래대로 쫙 펴서 **세션 복원** 수행 | 전처리 |
| **탐지 엔진** | **시그니처/이상 탐지** 기반 진짜 해킹 공격인지 잡아냄 | 분석 핵심 |
| **정책 엔진** | 룰에 맞춰서 "이건 냅둬라", "이건 차단해라" **판단 내림** | 룰 매칭 |
| **대응 장치** | **IDS** 기반 경보(Log)만 띄우고, **IPS** 기반 트래픽을 찢어버림 | 집행관 |
| **이벤트 저장소** | 나중에 보고서 쓰려고 해킹 기록이랑 패킷 증거 모아둠 | 로그 저장 |

#### 한줄 요약

- 찢어진 패킷 이어 붙이고(정규화), 전단지 대조해서(탐지), 진짜면 핵심 제어 메커니즘 깬다(대응).

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **경로 외 배치(Out-of-band Deployment)**: 랜선에 직접 안 끼어들고, 옆에서 트래픽 복사본(Mirroring)만 넘겨받아 감시하는 쫄보 세팅(IDS)이다.
- **인라인 배치(Inline Deployment)**: 랜선 한가운데 떡하니 막아 서서 모든 트래픽이 자기를 무조건 거쳐 가게 만드는 일진 세팅(IPS)이다.

</details>

```text
[ IDS/IPS 탐지 및 차단 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [세션 복원] 트래픽 캡처   │
│ (해커가 찢어 보낸 패킷 조립) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [위협 분석] 탐지 엔진     │
│ (시그니처 매칭 & 이상 징후)  │
└──────────────┬───────────────┘
               ├── (공격 미탐지) ──▶ (무사 통과)
               ▼ (해커 발견!)
┌──────────────────────────────┐
│ 3. [정책 판정] 정책 엔진     │
│ (이거 진짜 해커 맞아? 오탐 아냐?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [대응 집행]               │
│ ├── IDS: 경보만 울리고 냅둠 │
│ └── IPS: 즉시 연결 끊고 차단│
└──────────────────────────────┘
```

### 동작 원리

1. 정규화 세션 전달: 조각•중복•순서 차이를 제거한 통신 흐름 복원.
2. 탐지 결과 전달: **시그니처/이상 탐지** 기반 공격 신뢰도를 계산.
3. 대응 명령: **IDS** 경보(로그)와 **IPS** 차단(Drop) 중 정책에 맞는 조치 집행.

#### 한줄 요약

- 트래픽 캡처 $\to$ 해커 스캔 $\to$ 오탐 확인 $\to$ 경보(IDS) 띄우거나 모가지 썰기(IPS)

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **오탐(False Positive)**: 평범한 직원 PC인데 "해커다!" 하고 사이렌 울리고 차단해 버리는 양치기 소년(오판)이다. (IPS에서 치명적)
- **미탐(False Negative)**: 진짜 찐 해커가 들어왔는데 "어~ 통과~" 하고 바보처럼 뚫려버리는 최악의 보안 사고다.

</details>

| 구분 | **IDS (감시 카메라)** | **IPS (경호원)** |
|:---|:---|:---|
| 적용 기준 | 가시성 확보 및 새로운 탐지 규칙 검증 | 고신뢰도 위협의 즉각적이고 실시간 타격 차단 |
| 핵심 특징 | **경로 외(Out-of-band)** (트래픽 복제본 수신) | **인라인(Inline)** (트래픽 무조건 통과해야 함) |
| 단점 및 한계 | 해킹 진행 중에도 구경만 하고 **경보만 띡 띄움** | 오탐 발생 시 정상 서비스 짤림 / 장비 죽으면 망 뻗음 |

#### 한줄 요약

- IDS는 해커가 털어갈 때 소리만 지르고, IPS는 멱살을 잡지만 엉뚱한 사람 멱살(오탐) 잡을 위험이 크다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Fail-Open**: IPS 장비가 과부하로 뻗어버렸을 때, "그냥 문 다 열어!" 하고 통신을 살리는 비상 모드다. (보안은 뚫리지만 서비스는 유지)
- **Fail-Close**: 장비가 뻗으면 "아무도 못 지나가!" 하고 문을 콱 닫아버리는 모드다. (보안은 지키지만 서비스는 뻗음)

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 빡세게 탐지했더니 **정상 고객을 해커로 오해해서 차단함(오탐)** | 탐지 신뢰도(Confidence)와 자산 중요도를 결합해 튜닝 | 무고한 접속 차단 방지 및 고객 민원 급격한 저하 |
| 해커가 패킷을 잘게 쪼개거나 꼬아서 **시그니처를 피함** | 찢어진 패킷 원상 복구하는 **세션 정규화/복원** 강화 | 꼼수 부리는 변형 우회 공격(Evasion) 완벽 탐지 |
| 해커가 HTTPS 암호화해서 쏘니까 **IPS가 짐칸 내용물을 못 봄** | SSL 복호화 장비나 인증서 연동으로 가시성 확보 | 암호화 트래픽 딥 스캔 가능 |
| 인라인 IPS 장비가 뻗어버려서 **인터넷 전체가 마비됨** | IPS 죽으면 랜선 기계적으로 잇는 **Fail-Open (Bypass)** | IPS 뻗어도 정상 서비스는 안 끊기고 살아남음 |

#### 한줄 요약

- 정상 트래픽 짜르지 않게 조심하고(오탐 방지), 뻗으면 무조건 랜선 뚫어줘라(Fail-Open).

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **바이패스(Bypass)**: IPS 장비가 뻗었을 때 릴레이 스위치가 딸깍 붙어서 랜선을 물리적으로 이어버리고 트래픽이 쌩 지나가게 만드는 하드웨어 꼼수다.

</details>

- 신규 룰은 **IDS 모드** 기반 오탐을 검증하고, 확실한 공격만 **IPS 모드** 기반 즉각 차단하며 장애 시 **바이패스(Fail-Open)** 를 확보하는 점진적 차단 기조 확립함

#### 한줄 요약

- 무작정 IPS 켜서 정상 유저 다 쫓아내지 말고, IDS로 충분히 간 본 다음에 확실한 해커만 때려잡아라.
