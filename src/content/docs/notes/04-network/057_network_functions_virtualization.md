## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NFV (네트워크 기능 가상화, Network Functions Virtualization)**: 비싼 시스코 장비 대신 동네 컴퓨터(범용 서버)를 사다가, 방화벽이나 라우터 프로그램만 깔아서 똑같이 써먹는 짠돌이 기술이다.
- **VNF / CNF (가상 모듈)**: 전용 장비 안에 들어있던 하드웨어 기능만 쏙 빼서, VMWare(가상머신)나 도커(컨테이너) 형태로 묶어놓은 소프트웨어 파일이다.

</details>

- 정의: **네트워크 기능 가상화**는 수천만 원짜리 전용 하드웨어 장비를 버리고, 싸구려 범용 서버(COTS) 위에 네트워크 기능을 가상화(VNF/CNF)하여 소프트웨어로 돌리는 ETSI 표준 아키텍처다.
- 배경: 통신사들이 트래픽 늘어날 때마다 비싼 외산 장비를 계속 사야 해서 돈(CAPEX/OPEX)이 거덜 나니까, **"그냥 조립 PC에 프로그램만 올려서 쓰면 안 되나?" 하고 뭉쳐서 만들었다.**

#### 한줄 요약

- 통신사들이 비싼 벤더 전용 장비 사기 돈 아까워서, 남는 범용 서버에 윈도우 깔듯 '가짜 라우터' 소프트웨어 돌리는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MANO (관리 및 오케스트레이터)**: 가상 방화벽이나 라우터들이 뻗지 않게 24시간 감시하다가, 트래픽이 몰리면 자동으로 복사본을 찍어내고 트래픽 빠지면 지워버리는 공장장(오토스케일링)이다.

</details>

- **장비 종속 탈출 (디커플링)**: 비싼 벤더 전용 장비(하드웨어+소프트웨어 일체형)를 찢어발겨서, 하드웨어는 아무거나 쓰고 소프트웨어만 올리면 되게 족쇄를 풀었다.
- **공장장(MANO)의 풀오토 통제**: 버튼 하나만 누르면 방화벽이 깔리고, 라우터가 지워지는 등 인프라 깔고 지우는 노가다를 완전 자동화했다.
- **고무줄 확장성 (오토스케일링)**: 명절에 접속자 폭주하면 방화벽 가상머신(VM)을 10개로 뻥튀기하고, 새벽엔 1개로 줄이는 등 자원을 탄력적으로 아껴 쓴다.

#### 한줄 요약

- 하드웨어 껍데기를 버리고, 공장장(MANO)이 트래픽 눈치 봐서 가짜 장비(VM)를 찍어냈다 지웠다 하는 자동화 체계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NFVO (서비스 오케스트레이터)**: 전체 그림을 그리는 총괄 설계자다. "여긴 방화벽 놓고 저긴 라우터 놔라" 지시한다.
- **VNFM (VNF 매니저)**: 방화벽이나 라우터(VNF) 하나하나의 멱살을 잡고, 켜고 끄고 복사하는 직속 소프트웨어 팀장이다.
- **VIM (가상 인프라 매니저)**: CPU, 메모리, 하드디스크 같은 물리 자원 쪼가리들을 긁어모아서 가상 서버로 만들어주는 밑바닥 노가다 반장(OpenStack 등)이다.
- **NFVI (NFV 인프라)**: 동네 컴퓨터 가게에서 사 온 흔해 빠진 조립 서버, 랜카드 쪼가리 등 하드웨어 베이스다.

</details>

```text
[ NFV 가상화 직관적 비교 구조 ]

[ 오케스트레이션 (MANO) ] ── (공장장)
  ├─ NFVO (총괄 설계자)
  ├─ VNFM (소프트웨어 팀장)
  └─ VIM (하드웨어 노가다 반장)

[ 가상 기능 (VNF / CNF) ] ── (가짜 방화벽, 짭 라우터 파일)

[ 물리 인프라 (NFVI) ] ── (비싼 시스코 장비 대신 쓰는 범용 PC)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **NFVO (총괄 설계자)** | "여긴 방화벽 놓고 여긴 라우터 놔"라고 **전체 도면 그리는 사장님** | MANO 계층 |
| **VNFM (소프트웨어 팀장)**| 사장님 지시받아서 가상 방화벽(VNF) **설치하고 삭제하는 중간 관리자** | MANO 계층 |
| **VIM (하드웨어 반장)** | 밑바닥 CPU랑 메모리 쪼가리들 모아서 **가상 서버로 조립해 주는 반장** | MANO 계층 |
| **VNF / CNF (가상 장비)** | 하드웨어 껍데기 없이 소프트웨어로만 돌아가는 **가짜 방화벽, 짭라우터** | Execution 계층 |
| **NFVI (물리 인프라)** | 비싼 외산 장비 버리고 들여온 **싸구려 범용 조립 PC와 랜카드들** | Execution 계층 |

#### 한줄 요약

- 사장(NFVO)이 도면 그리면 반장(VIM)이 조립 PC 뜯어오고, 팀장(VNFM)이 짭라우터(VNF) 켜서 돌리는 환상의 팀워크 구조.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NSD (네트워크 서비스 명세)**: 사장님(NFVO)한테 주문할 때 쓰는 견적서다. "CPU 2개짜리 방화벽 1대랑 라우터 1대 묶어주세요"가 적혀 있다.

</details>

```text
[ NFV 가상 방화벽 찍어내기 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [방화벽 설치 주문 접수]   │
│ (운용자: 방화벽 하나 급하게 깔아줘!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [NFVO $\to$ VIM 자원 구걸]  │
│ (사장님: 야 반장! CPU 2개랑 램 4기가 좀 빼와라)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [VIM $\to$ VNFM 자원 확보]  │
│ (반장: 자원 빼왔음. 이제 팀장이 프로그램 까셈)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [VNFM 가상 장비(VNF) 부팅]│
│ (팀장: 가짜 방화벽 소프트웨어 켰다! 일해라!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [오토스케일링 무한 감시]  │
│ (트래픽 터지면 1번부터 알아서 공장장이 또 찍어냄)
└──────────────────────────────┘
```

### 동작 원리

1. 설치 주문: OSS/BSS에서 방화벽 좀 깔아달라고 청사진(NSD)을 던짐.
2. 자원 요구: 사장(NFVO)이 반장(VIM)한테 물리 자원 좀 할당하라고 시킴.
3. 자원 확보: VIM이 깡통 서버에서 CPU랑 램을 떼와서 준비 완료 때림.
4. 가상머신 부팅: 팀장(VNFM)이 가상 방화벽(VNF) 파일을 디스크에 풀고 부팅(인스턴스화)시킴.
5. 오토스케일링 감시: 켜진 방화벽 상태를 지켜보다가 뻗을 거 같으면 알아서 더 찍어냄.

#### 한줄 요약

- 주문 들어오면 자원 떼오고, VM 부팅시킨 다음에, 뻗을까 봐 24시간 감시하는 풀오토 공장이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전용 어플라이언스 (하드웨어 일체형)**: 하드웨어 껍데기랑 소프트웨어를 절대 못 뜯게 강력 본드로 붙여놓고 엄청 비싸게 파는 기존 시스코/주니퍼 장비다.

</details>

| 비교 항목 | **NFV (소프트웨어 가상화)** | **전용 하드웨어 (어플라이언스)** |
|:---|:---|:---|
| 비유 및 핵심 특징 | 남는 조립 PC에 **VM 깔아 쓰는 가성비충** | 옵션 질 떡칠 된 **포르쉐 풀옵션** |
| 하드웨어 가용성 | 벤더 종속 없이 **아무 컴퓨터나 사다 쓰면 됨** | 제조사 전용 칩(ASIC) 박힌 **자기들만의 장비** |
| 설치 및 확장 속도 | 마우스 클릭하면 **1분 만에 VM 하나가 뚝딱** | 주문하고 배송 오면 **랜선 꼽아야 켜짐 (한 달 걸림)** |
| 하드웨어 성능 | 소프트웨어로 억지로 돌리니까 **속도 까먹음 (오버헤드)** | 전용 하드웨어 칩이 직접 까니까 **빠르고 확실함** |
| 초기 비용 (CAPEX)| 남는 서버 떼다 쓰면 되니까 **초기 비용 떡락함** | 장비마다 수천만 원짜리 청구서가 날아옴 **(개비쌈)** |

#### 한줄 요약

- NFV는 가성비가 쩔고 확장하기 좋지만 가상화 오버헤드 때문에 좀 느리고, 전용 장비는 무식하게 비싸지만 깡성능은 압도적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DPDK / SR-IOV (하드웨어 가속기)**: 가상머신(VM)에서 랜카드로 패킷 보낼 때 윈도우 커널(OS) 거치면서 속도 까먹는 걸 막으려고, 랜카드랑 다이렉트로 고속도로를 뚫어주는 부스터다.
- **서비스 체이닝 (SFC)**: 트래픽이 들어올 때 "방화벽 거치고 $\to$ L4 거치고 $\to$ 라우터 타라"고 랜선 꼽지 않아도 마우스 드래그로 소프트웨어 순서를 엮어주는 논리적 쇠사슬이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 짭라우터(VM) 돌리니까 **랜카드 속도가 반 토막 남** | 하이퍼바이저랑 커널 거치면서 소프트웨어 연산 오버헤드가 터짐 | OS 커널 다 쌩까고 랜카드랑 다이렉트로 꽂아버리는 **DPDK / SR-IOV 부스터 장착** | 전용 장비 급의 무식한 패킷 처리 속도(Gbps) 복구 |
| 가상 장비들끼리 **데이터 토스하다가 길 잃고 뻗음** | 방화벽 거치고 L4 가야 하는데 중간에 가상 랜선(체인)이 꼬여버림 | 헤더에 순서를 박아 넣고 알아서 길 찾아가는 **NSH 기반 SFC (서비스 체이닝) 세팅** | 물리 랜선 꼽고 뺄 필요 없이 깔끔한 트래픽 순서 제어 |
| 옆 동네 CPU 메모리 쓰다가 **핑 지연(Latency) 오지게 튐** | NUMA 구조상 자기 소켓 코어 밖의 메모리까지 원정 끌어 쓰면 딜레이 생김 | 가상 장비(VNF)를 특정 CPU 코어에 강력 본드로 붙여버리는 **CPU Pinning (고립) 적용** | 원정 메모리 딜레이 컷트하고 초고속 패킷 반응 유지 |

#### 한줄 요약

- 속도 까먹는 건 부스터(DPDK) 달아서 해결하고, 데이터 순서 꼬이는 건 쇠사슬(SFC)로 묶고, 핑 튀는 건 CPU 본드질(Pinning) 해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 전용 하드웨어 어플라이언스의 엄청난 도입 비용(CAPEX)과 벤더 종속(Lock-in)을 끊어내기 위해, 범용 서버(COTS) 기반의 **VNF/CNF 기능 분리**와 **MANO 오케스트레이션**을 결합한 NFV 기조 확립함

#### 한줄 요약

- NFV는 통신사들이 하드웨어 전담자에서 탈출해 소프트웨어 권력을 쥐기 위해 쏘아 올린 네트워크의 산업 혁명이다.
