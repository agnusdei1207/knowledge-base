## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SDN (소프트웨어 정의 네트워킹)**: 라우터마다 일일이 들어가서 설정하던 노가다를 끝내고, 중앙 통제실(컨트롤러)에서 마우스 클릭 한 번으로 수백 대의 장비 길을 쫙 뚫어주는 마법의 자동화 네트워크 아키텍처다.
- **제어 평면 / 데이터 평면 분리**: 라우터의 똑똑한 뇌(길 찾기, 제어 평면)는 뽑아서 중앙 서버로 보내버리고, 라우터는 뇌 빼고 중앙에서 시키는 대로 패킷만 나르는 멍청한 택배 기사(데이터 평면)로 만들어버린 구조다.

</details>

- 정의: **SDN**은 똑똑한 머리(제어 평면)와 무식한 몸통(데이터 평면)을 물리적으로 쪼개서, 중앙 컨트롤러라는 큰 형님이 오픈 API 소프트웨어로 전국의 네트워크망을 원격 조종하는 기술이다.
- 배경: 옛날엔 장비 하나 고장 나면 관리자가 랜선 꼽고 검은 화면(CLI)에서 밤새 타자 치면서 라우터 설정을 맞춰줘야 했는데, **이 무식한 노가다를 클라우드 시대에 맞게 원클릭으로 싹 다 자동화하려고 도입했다.**

#### 한줄 요약

- 장비마다 뇌(제어)를 뽑아서 중앙 서버에 몰아넣고, 남은 깡통 장비들을 소프트웨어(코딩)로 원격 조종하는 혁명적인 네트워크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중앙 집중식 제어 (Logical Centralized Control)**: 라우터 수백 대가 각자 지 맘대로 길을 찾는 게 아니라, 중앙에 있는 컨트롤러가 하늘에서 전체 지도를 싹 다 내려다보면서 안 막히는 길을 딱딱 찍어주는 거다.
- **오픈 API (NBI / SBI)**: 대장이 위쪽 응용 앱이랑 말할 때 쓰는 통신 규격(NBI)과, 아래쪽 깡통 스위치들한테 명령 내릴 때 쓰는 규격(SBI/OpenFlow)의 표준 언어다.

</details>

- **뇌와 몸통의 물리적 분리**: 스위치는 "어디로 갈지 묻지 마라, 난 시키는 대로 패킷만 나른다" 상태(데이터 평면)가 되고, 경로는 오직 중앙 컨트롤러(제어 평면)가 짠다.
- **신의 시야 (전역 토폴로지 기반 최적화)**: 중앙 컨트롤러가 전국 도로망 현황을 실시간으로 다 꿰고 있어서, 병목이나 핑 튀는 구간을 피해 기가 막힌 우회로(트래픽 엔지니어링)를 뚫어준다.
- **코드(SW)로 굴리는 네트워크 자동화**: 밤새 스위치 앞에서 CLI 치던 네트워크 아재들은 가고, 이제 파이썬 코딩(NetDevOps) 한 줄로 전국의 방화벽과 라우팅 정책을 갈아엎는 시대가 열렸다.

#### 한줄 요약

- 제어 뇌와 전달 몸통을 찢어 놓고, 전역 지도를 보는 컨트롤러가 코딩 한 줄로 전체 망을 통제하는 게 핵심 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SDN 컨트롤러 (SDN Controller)**: SDN 네트워크의 신이자 두뇌다. 밑에서 올라오는 온갖 보고를 받고 "너는 이쪽 길로 가고 넌 폐기해!" 하고 룰을 꽂아준다.
- **오픈플로우 (OpenFlow / SBI)**: 컨트롤러가 멍청해진 스위치들한테 "IP가 1.1.1.1이면 3번 포트로 던져라" 하고 룰(흐름 규칙)을 주입할 때 쓰는 사우스바운드 API의 근본 프로토콜이다.

</details>

```text
[ SDN 3계층 팩트 폭행 구조 ]

[ 1. 응용 계층 (네트워크 방화벽, QoS 앱) ] ── (우리가 셋팅하고 싶은 목표값)
      │
  (노스바운드 API - NBI) : 앱이랑 대장 사이의 통역기 (RESTful)
      ▼
[ 2. 제어 계층 (SDN 컨트롤러) ] ── (전국 망을 통제하는 빅브라더 두뇌)
      │
  (사우스바운드 API - SBI / OpenFlow) : 대장이 쫄따구 스위치들한테 내리는 명령
      ▼
[ 3. 인프라 계층 (멍청해진 화이트박스 스위치들) ] ── (생각 없이 명령대로 패킷만 고속으로 나름)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **응용 계층 (Application Layer)** | "철수 IP는 막고 영희는 10기가 보장해"라고 **비즈니스 룰을 짜는 사장님** | App |
| **노스바운드 API (NBI)** | 사장님(앱)의 명령을 컨트롤러가 알아듣게 전달해 주는 **비서 (주로 REST API 씀)** | NBI |
| **제어 계층 (SDN 컨트롤러)** | 전국 지도를 펴놓고 **어디로 패킷을 보낼지 머리 굴려서 스위치에 명령 꽂는 두뇌** | Control |
| **사우스바운드 API (SBI)** | 컨트롤러가 깡통 스위치들한테 룰을 주입할 때 쓰는 **명령어 규격 (OpenFlow가 근본임)** | SBI |
| **인프라 계층 (스위치 장비)** | 대장(컨트롤러)이 시킨 대로 뇌 빼고 무지성으로 **택배(패킷)만 빡세게 나르는 깡통 장비** | Infra |

#### 한줄 요약

- 앱(사장님)이 NBI로 명령하면 $\to$ 컨트롤러(두뇌)가 전역 지도를 보고 길을 찾아서 $\to$ SBI(OpenFlow)로 깡통 스위치들한테 룰을 주입한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **의도 기반 네트워킹 (Intent-Driven Networking)**: 운용자가 "포트 80 닫고 OSPF 10" 이렇게 복잡하게 명령 안 하고, 그냥 "사내 보안 강화해 줘" 하면 AI 알아서 세팅이 쫙 바뀌는 개사기 매크로다.

</details>

```text
[ SDN 원클릭 망 제어 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [네트워크 의도/정책 입력] │
│ (사장님: A부서부터 B부서까지 길 10기가로 뚫어라)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [전국 토폴로지(지도) 스캔]│
│ (컨트롤러: 흠... 지금 서울 쪽 막히고 부산 쪽 비어있음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [최적의 꿀길 연산 및 룰 생성]
│ (컨트롤러: 그럼 부산 쪽으로 우회하는 룰 생성 완료)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [OpenFlow 룰 하향 설치 (SBI)]
│ (컨트롤러 $\to$ 스위치들: 자, 이거 받아서 이대로만 해라)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [AI 텔레메트리 폐루프 감시]│
│ (전파 쏘다가 막히면 2번부터 알아서 AI가 다시 돌림)
└──────────────────────────────┘
```

### 동작 원리

1. 정책 입력: 응용 계층에서 요구사항(Intent)을 NBI를 통해 컨트롤러에 접수함.
2. 토폴로지 스캔: 컨트롤러가 전체 네트워크 지도를 쫙 펴고 텔레메트리(현재 교통 상황)를 수집함.
3. 흐름 연산: 핑 튀는 구간 피해서 제일 안 막히고 빠른 최적의 길(Flow Rule)을 계산해 냄.
4. SBI 하향 설치: 계산된 흐름 규칙(Flow Table)을 사우스바운드(OpenFlow)를 통해 밑바닥 스위치들에 쫙 주입함.
5. 폐루프 감시: 통신 중에 장애 나면 AI 텔레메트리가 즉각 감지해서 다시 2번으로 돌아가 우회로를 뚫어버림.

#### 한줄 요약

- 의도 입력 $\to$ 전체 지도 스캔 $\to$ 최적 길 찾기 $\to$ 깡통 스위치에 룰 쑤셔 넣기 $\to$ 24시간 자동 감시의 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **분산 제어 (전통적 라우팅)**: 중앙 통제 대장 없이, 동네 라우터끼리 "야 너네 길 뚫렸냐?" 하고 OSPF/BGP로 수군대면서 각자 알아서 눈치껏 길을 찾는 아날로그 방식이다.

</details>

| 비교 항목 | **SDN (소프트웨어 정의 네트워킹)** | **전통적 IP 네트워크 (기존 라우터)** |
|:---|:---|:---|
| 팩트 폭행 비유 | **중앙 통제실에서 싹 다 조종하는 드론쇼** | **각자 알아서 눈치껏 운전하는 택시 기사들** |
| 두뇌(제어) 위치 | 뇌는 다 뽑아서 **중앙 컨트롤러**가 독점함 | 장비마다 뇌(제어 평면)가 하나씩 다 달려 있음 **(분산됨)** |
| 망 설정 방식 | **마우스 원클릭, 파이썬 코딩 한 줄 (자동화)** | 장비마다 콘솔선 꼽고 **CLI(검은 화면) 밤샘 타자** |
| 길 찾기 시야 | **전국 지도를 한눈에 보며** 길을 뚫음 (전역 뷰) | **자기 주변 동네 상황**만 보고 길을 찾음 (국소 뷰) |
| 장비 단가 | 뇌 빠진 깡통 스위치라 **개당 단가 떡락함 (화이트박스)** | 벤더사(시스코 등) 특허 기술 떡칠해서 **개비쌈 (종속됨)** |

#### 한줄 요약

- 예전엔 장비마다 비싼 뇌를 달아주고 일일이 세팅해야 했지만, SDN은 중앙에 큰 뇌 하나 두고 깡통들을 원격 조종해서 돈과 시간을 오지게 아낀다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SPOF (단일 장애점)**: 대장(컨트롤러)이 뻗으면 밑에 깡통 스위치들이 길을 못 찾아서 전국 통신망이 동시에 싹 다 뒤져버리는 SDN 최대의 아킬레스건이다.
- **TCAM (스위치 하드웨어 메모리)**: 스위치가 대장한테 받은 규칙(Flow Rule)을 적어두는 초고속 비싼 메모린데, 이게 용량이 쥐꼬리만 해서 규칙 꽉 차면 뻗는다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 컨트롤러(대장) 뻗으면 **전국 통신망 다 뒤짐 (SPOF)** | 뇌가 하나뿐인데 그 뇌가 해킹당하거나 서버 전원이 나가면 끝남 | 컨트롤러 서버를 여러 대 두고 **Raft(분산 합의) 클러스터링 동기화 적용** | 대장 서버 하나 죽어도 부대장이 바로 지휘권 무손실 인수 |
| 스위치가 뻑하면 컨트롤러한테 **"어떡함?" 하고 징징댐** | 처음 보는 패킷(Packet-In) 오면 깡통 스위치가 감당 못 하고 대장한테 다 토스함 | 컨트롤러 CPU 뻗지 않게 **P4(데이터 평면 프로그래밍)로 1차 필터링 컷트시킴** | 컨트롤러 과부하 폭주 막고 스위치 자립심 향상 |
| 스위치 머리통 꽉 차서 **길 찾기 룰을 더 못 외움** | 비싼 TCAM 메모리 용량이 작아서 안 쓰는 쓰레기 룰들이 꽉 차 있음 | 안 쓰는 룰은 바로바로 지워버리는 **Idle/Hard Timeout 최적화 가동** | TCAM 자원 고갈 원천 차단 및 초고속 스위칭 생존 |

#### 한줄 요약

- 뇌(컨트롤러) 죽을까 봐 클러스터링(Raft) 해두고, 깡통 스위치가 징징대는 건 P4로 막고, 비싼 메모리(TCAM)는 제때제때 청소해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 고가의 하드웨어 벤더 종속(Lock-in)과 분산 제어의 끔찍한 관리 오버헤드를 극복하기 위해, **제어 평면과 데이터 평면을 물리적으로 분리**하고 논리적 중앙 컨트롤러를 올린 SDN 아키텍처 기조 확립함

#### 한줄 요약

- SDN은 "스위치는 생각하지 마라, 길은 내가 뚫어준다"는 마인드로 깡통 장비들을 모아 글로벌 네트워크를 코딩 한 줄로 지휘하는 신의 기술이다.
