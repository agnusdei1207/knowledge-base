## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 프로토콜 3요소(Network Protocol 3 Elements)**: 기계들끼리 대화할 때 문법(구문), 뜻(의미), 타이밍(속도/순서) 3박자가 딱 맞아야 에러 안 나고 통신이 된다는 절대 3규칙이다.
- **상호운용성(Interoperability)**: 아이폰이든 갤럭시든, 이 3요소 룰만 지키면 서로 막힘없이 데이터를 주고받을 수 있는 능력이다.

</details>

- 정의: 네트워크 통신 규약을 구성하는 필수 3박자인 **구문(Syntax)·의미(Semantics)·타이밍(Timing)**
- 배경: 셋 중 하나라도 어긋나면 이기종 장비 간에 말이 안 통해서 **네트워크 상호운용이 박살 나기 때문** #### 한줄 요약

- 통신할 때 문법, 의미, 박자(속도) 3개가 다 맞아야 기계끼리 말이 통한다는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **구문(Syntax)**: "데이터를 0과 1로 어떻게 나열할까?" 하는 형식적인 문법(메시지 포맷, 헤더 구조)이다.
- **의미(Semantics)**: "이 0과 1이 무슨 뜻이고, 받으면 무슨 행동을 해야 할까?" 하는 제어 동작(에러 처리, 응답)이다.
- **타이밍(Timing)**: "얼마나 빨리 보내야 안 체할까? 대답 안 오면 언제 다시 보낼까?" 하는 속도와 순서 조절이다.

</details>

- **구문(Syntax)**: 패킷 구조, 필드 크기, 데이터 포맷 등 0과 1의 형식을 맞춤.
- **의미(Semantics)**: 플래그 해석, 제어 동작, 에러 처리 등 진짜 뜻을 해석함.
- **타이밍(Timing)**: 언제 보낼지, 얼마나 빨리 보낼지, 순서는 어떻게 할지 속도를 조율함.

#### 한줄 요약

- 포맷(구문)을 맞추고, 뜻(의미)을 해석하고, 속도(타이밍)를 맞추는 3박자가 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **필드(Field)**: 프로토콜 메시지 안에서 "여긴 IP 주소칸, 저긴 포트 번호칸" 하고 자리를 만들어 놓은 논리적 구역이다.
- **인코딩(Encoding)**: 글자나 사진을 랜선으로 쏘기 위해 0과 1의 비트 패턴으로 변환하는 규격이다.

</details>

```text
[ 프로토콜 3요소 직관적 비교 아키텍처 ]

[ 송신자 ] ───────────────────────────────────────── [ 수신자 ]
   │                                                    ▲
   │ 1. 구문 (Syntax)   : "01001001" (헤더 포맷 조립)       │
   │                                                    │
   │ 2. 의미 (Semantics): "이건 연결 요청(SYN)이야"         │
   │                                                    │
   ▼ 3. 타이밍 (Timing) : "초당 10번만 천천히 보냄"         │
[ 01001001 011100.. (랜선 통과) ] ───────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **구문 (Syntax)** | 비트를 쪼개서 포맷, 헤더 길이, 인코딩 방식을 맞추는 **형식 경찰** |
| **의미 (Semantics)**| 플래그(SYN/ACK)를 보고 에러 처리나 연결 응답 같은 **동작을 지시하는 대장** |
| **타이밍 (Timing)** | 너무 빠르면 늦추고, 응답 없으면 재전송(Timeout) 시키는 **속도/순서 조절자** |

#### 한줄 요약

- 구문 경찰이 포맷을 잡고, 의미 대장이 명령을 내리면, 타이밍 조절자가 박자를 맞춘다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 전이(State Transition)**: 의미(Semantics) 요소에 따라, '대기' 상태에서 메시지를 받고 '연결 완료' 상태로 넘어가는 과정이다.
- **타임아웃(Timeout)**: 타이밍(Timing) 요소의 핵심으로, 3초 안에 대답 안 오면 "죽었나?" 하고 재전송을 때리는 임계 시간이다.

</details>

```text
[ 수신자의 3요소 처리 십자포화 흐름 ]
┌──────────────────────────────┐
│ 0과 1의 전기 신호 뭉치 수신  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. 구문 해석 (Syntax)        │
│ (길이 맞는지 자 대고 잘라봄) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 의미 해석 (Semantics)     │
│ (ACK 플래그네? 연결 성공!)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 타이밍 제어 (Timing)      │
│ (응답 타이머 끄고 다음 거 쏨)│
└──────────────────────────────┘
```

### 동작 원리

1. 데이터 수신: 랜선 타고 비트 뭉치가 들어옴.
2. 구문 해석: 헤더 형식과 비트 길이에 맞게 덩어리를 예쁘게 자름.
3. 의미 해석: 잘라낸 필드의 제어 코드(SYN, ACK 등)가 무슨 뜻인지 파악함.
4. 상태 전이: 뜻을 알았으니 그에 맞게 동작(연결 승인, 에러 처리 등)을 수행함.
5. 타이밍 제어: 너무 빨리 왔으면 천천히 보내라(흐름 제어)고 알려주거나 응답을 보냄.

#### 한줄 요약

- 자 대고 자르고(구문) $\to$ 뜻을 파악해서 행동하고(의미) $\to$ 박자 맞춰서 답장(타이밍)하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **프로토콜 적합성(Protocol Conformance)**: 니가 만든 통신 장비가 국제 표준(RFC)의 구문, 의미, 타이밍 3요소를 완벽하게 지켰는지 체크하는 증명서이다.

</details>

| 분석 관점 | **어긋났을 때 발생하는 직관적 비교(증상)** | **대응 솔루션** |
|:---|:---|:---|
| **구문 결함 (Syntax)** | 길이나 포맷이 달라서 패킷이 쓰레기로 인식되고 **바로 드롭됨** | 와이어샤크(Wireshark)로 패킷 까서 비트 단위 검증 |
| **의미 결함 (Semantics)**| 포맷은 맞는데 "이게 뭔 소리야?" 하고 **엉뚱한 에러 응답 반환함** | 프로토콜 적합성 테스트 도구로 상태 전이 확인 |
| **타이밍 결함 (Timing)** | 서로 말이 안 맞아서 **계속 재전송하거나 세션이 끊김(타임아웃)** | 네트워크 에뮬레이터로 지연(RTT) 테스트 |

#### 한줄 요약

- 구문 틀리면 버려지고, 의미 틀리면 헛소리하고, 타이밍 틀리면 답답해서 끊겨버린다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상태표(State Table)**: "이 신호가 오면 무조건 이렇게 행동해라" 하고 경우의 수를 표로 다 박아놔서 기계가 버벅대지 않게 만든 명세서이다.
- **버전 협상(Version Negotiation)**: 구식 장비랑 최신 장비가 만나면 "나 옛날 문법(구문)밖에 모름" "ㅇㅋ 옛날 방식으로 맞춰드림" 하고 스펙을 맞추는 합의 과정이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비트 읽는 순서(엔디안)가 달라서 파싱 오류(구문 결함) 터짐 | 구문 명세서에 **비트/바이트 순서(Endinan) 빡세게 정의** | 데이터 오해석 원천 차단 |
| 예외 상황에서 기계가 어떻게 할지 몰라 먹통됨(의미 결함) | 모든 경우의 수를 박아 넣은 **상태표(State Table) 설계** | 무한 루프 및 시스템 교착 예방 |
| 핑 튀어서 맨날 타임아웃 걸리고 끊김(타이밍 결함) | 망 지연(RTT)에 맞춰 **동적 RTO 조절 및 버전 협상** 적용 | 재전송 폭주 방지 및 통신 유지 |

#### 한줄 요약

- 순서(엔디안) 맞추고, 경우의 수(상태표) 다 적어두고, 옛날 장비 만나면 맞춰줘라(협상).

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **검증 순서 결정(Verification Ordering)**: 통신 에러 나면 냅다 재부팅하지 말고, 패킷 생김새(구문) $\to$ 뜻(의미) $\to$ 속도(타이밍) 순으로 원인을 까보는 진단 기법이다.

</details>

- **검증 순서 결정** 원칙에 따라, 통신 연동 장애 시 **구문(패킷 파싱) $\to$ 의미(상태 응답) $\to$ 타이밍(타임아웃)** 순서로 결함을 국소화하는 기조 확립함

#### 한줄 요약

- 통신 안 될 땐 무지성으로 찍지 말고 3요소 순서대로 체크해서 범인을 잡아라.
