## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Protocol 3 Elements (프로토콜 3요소)**: 이기종 시스템 간 원활한 데이터 교환을 위해 반드시 정의되어야 하는 Syntax(구문), Semantics(의미), Timing(타이밍).
- **Interoperability (상호운용성)**: 서로 다른 기종 및 벤더의 통신 장비가 공통된 프로토콜 규칙을 준수하여 정보 왜곡 없이 상호 통신할 수 있는 능력.

</details>

- 정의/개념: 이기종 시스템 간의 통신 신뢰성과 상호운용성을 보장하기 위해 규정한 **구문(Syntax), 의미(Semantics), 타이밍(Timing) 3대 필수 요소**
- 배경/필요성: 표준화된 통신 규약 부재 시 발생하는 **비트 해석 오류, 제어 플래그 오작동, 전송 속도 불일치에 따른 패킷 손실 및 세션 단절 해결 불가**

#### 한줄 요약
- 데이터 형식(구문), 제어 동작(의미), 전송 속도 및 순서(타이밍)를 정의하여 상호운용성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Syntax (구문)**: 데이터의 물리적/논리적 형식, 비트 구성, 필드 길이, 문자 인코딩 체계.
- **Semantics (의미)**: 전송된 비트 패턴 및 제어 플래그가 지니는 의미와 오류 제어, 상태 전이 동작.
- **Timing (타이밍)**: 송수신 시스템 간의 통신 속도 일치(흐름 제어), 패킷 전송 순서화 및 타임아웃 주기 제어.

</details>

- 패킷 헤더 구조, 필드 크기, 엔디안을 정의하는 **구문(Syntax) 데이터 포맷**
- 제어 플래그(SYN/ACK)와 오류 복구 로직을 명시하는 **의미(Semantics) 제어 규칙**
- 흐름 제어, 혼잡 제어 및 타임아웃 주기를 통제하는 **타이밍(Timing) 속도 조율**

#### 한줄 요약
- 구문(형식 규정), 의미(동작 해석), 타이밍(속도 및 순서 제어)의 결합으로 통신 신뢰성을 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **State Transition Machine (상태 전이 머신)**: 수신된 패킷의 의미(Semantics)와 타이머 이벤트에 따라 통신 엔드포인트의 연결 상태(LISTEN, SYN_SENT, ESTABLISHED)를 전이시키는 제어 엔진.

</details>

```text
[프로토콜 3요소(Syntax, Semantics, Timing) 상호작용 구조]
|-- 1. Syntax Layer (데이터 형식: Header Format, Field Length, Big-Endian 인코딩)
`-- 2. Semantics Layer (제어 동작: SYN/ACK 플래그 해석, 에러 핸들링, 상태 머신 전이)
`-- 3. Timing Layer (전송 조율: Sliding Window 흐름제어, RTO 재전송 타이머, 속도 정합)
`-- 4. Communication Channel (이기종 호스트 간 신뢰성 패킷 송수신 및 세션 확립)
```

선의 의미: 계층 및 구문으로 조립된 패킷이 채널을 통해 전달되고 수신 측에서 의미를 해석하여 타이밍 제어 하에 상태를 전이하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **구문 (Syntax)** | 데이터 포맷, 신호 레벨, **패킷 헤더 구조, 문자 인코딩 및 필드 경계 정의** | 비트 포맷 명세 |
| **의미 (Semantics)** | 제어 플래그 해석, **오류 검출/정정 코드 처리, 요청에 대한 상태 전이 및 응답 행동 규정**| 제어 명령 해석 |
| **타이밍 (Timing)** | 송수신 속도 조율(흐름 제어), **패킷 전송 순서화, RTO(재전송 타임아웃) 주기 제어** | 속도/순서 정합 |

#### 한줄 요약
- 구문은 패킷 포맷을 검증하고, 의미는 제어 동작을 결정하며, 타이밍은 전송 속도와 순서를 조율한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **패킷 수신 처리 5단계**: 비트 스트림 수신 $\to$ 구문(Syntax) 무결성 파싱 $\to$ 의미(Semantics) 상태 전이 $\to$ 타이밍(Timing) 윈도우 조율 $\to$ 응답 반환.

</details>

```text
수신 호스트 패킷 도착 및 3요소 처리
        │
   1. [물리 신호 수신] 물리 계층으로부터 비트 스트림 수신 및 프레임 디코딩
        │
   2. [구문(Syntax) 검증] 헤더 길이, 체크섬 무결성, 필드 오프셋 정합성 파싱
   ┌────┴───────────────────────────┐
  구문 적합 (정상)                  구문 결함 (체크섬 오류/길이 불일치)
   │                                 │
3. [의미(Semantics) 해석]           • 패킷 즉시 폐기(Drop) 및 오류 로깅
   제어 플래그(SYN+ACK) 해석 및 상태 전이
   │
   ▼
4. [타이밍(Timing) 제어]
   수신 윈도우 크기(Window Size) 계산 및 RTO 타이머 재설정
   │
   ▼
5. [응답 및 완료]
   해석된 의미에 따라 ACK 응답 전송 및 후속 데이터 수신 대기
```

#### 한줄 요약
- 비트 수신 → 구문 파싱 → 의미 해석 → 타이밍 제어 → 응답 완료 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **프로토콜 3대 결함 유형**: 구문 결함(형식 불일치), 의미 결함(논리적 오동작), 타이밍 결함(속도/타임아웃 불일치).

</details>

| 비교 항목 | 구문 결함 (Syntax Error) | 의미 결함 (Semantics Error) | 타이밍 결함 (Timing Error) |
|:---|:---|:---|:---|
| **발생 원인** | **헤더 길이 불일치, 인코딩 오류, 패딩 누락** | **미정의 플래그 설정, 비정상 상태 전이 명령** | **송수신 속도 차이, 타임아웃 설정 오류, 지연**|
| **장애 현상** | **패킷 파싱 실패 및 즉각적인 패킷 폐기(Drop)**| **부적절한 에러 응답 반환 및 세션 비정상 종료**| **버퍼 오버플로우, 불필요한 재전송 폭주, 단절**|
| **영향 계층** | 프로토콜 디코딩 및 파싱 엔진 계층 | 비즈니스 로직 및 세션 상태 머신 계층 | 전송 흐름 제어 및 재전송 큐 관리 계층 |
| **검증 도구** | Wireshark 패킷 분석기, 포맷 유효성 검사기 | 프로토콜 적합성 테스트 도구, 상태 전이 검증기 | 네트워크 지연/지터 에뮬레이터, 부하 도구 |

#### 한줄 요약
- 구문 결함은 패킷 폐기를, 의미 결함은 논리적 오동작을, 타이밍 결함은 세션 지연 및 버퍼 오버플로우를 유발한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Big-Endian (네트워크 바이트 오더)**: 이기종 CPU 아키텍처 간의 바이트 순서 차이로 인한 파싱 왜곡을 방지하기 위해 네트워크 표준으로 규정된 바이트 배열 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CPU 아키텍처(x86 vs ARM) 간 바이트 순서 차이로 파싱 오류 | **네트워크 표준 전송 바이트 순서인 `Big-Endian (htons/htonl)` 강제** | 이기종 CPU 간 데이터 해석 오류 100% 방지 |
| 예외적 입력 시 정의되지 않은 상태 머신 진입으로 세션 교착 | **모든 입력 및 예외 케이스를 명시한 `완전 상태 전이표(State Table)` 설계**| 프로토콜 교착 및 비정상 세션 멈춤 차단 |
| 네트워크 지연 변동(Jitter)으로 인한 불필요한 조기 재전송 발생 | **Jacobson 알고리즘 기반 `동적 RTO(Retransmission Timeout)` 산정 적용**| 회선 대역폭 낭비 방지 및 혼잡 안정화 |
| 임의의 변조 패킷 인입으로 인한 버퍼 오버플로우 취약점 | **구문 검증 단계에서 `엄격한 필드 길이 및 경계 검사(Boundary Check)`** | 메모리 오염 보안 취약점 원천 차단 |

#### 한줄 요약
- 빅 엔디안 강제, 완전 상태 전이표 설계, 동적 RTO 산정, 엄격한 경계 검사로 운영한다.

## Ⅶ. 결론

- 이기종 분산 네트워크의 안정적인 상호운용성을 보장하기 위해 **구문(RFC 표준 포맷), 의미(상태 머신 명세), 타이밍(동적 흐름 및 혼잡 제어)의 3요소를 유기적으로 설계**하고, **Wireshark 적합성 검증과 동적 RTO 튜닝**을 결합하여 무결점 통신 아키텍처 완성

#### 한줄 요약
- 프로토콜 3요소는 데이터 형식(구문), 제어 동작(의미), 속도 및 순서(타이밍)를 정의하여 이기종 간 신뢰성 있는 통신을 보장하는 핵심 네트워크 설계 원리다.
