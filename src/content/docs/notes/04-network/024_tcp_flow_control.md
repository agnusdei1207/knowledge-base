## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TCP Flow Control (흐름 제어)**: 송수신 호스트 간 처리 속도 차이로 인한 수신 버퍼 오버플로우 및 패킷 폐기를 방지하는 종단 간 속도 조절 기술.
- **rwnd (Receive Window, 수신 윈도우)**: 수신 측이 현재 소켓 수신 버퍼의 여유 바이트 크기를 측정하여 TCP 헤더의 Window 필드로 송신 측에 광고하는 크기.

</details>

- 정의/개념: 수신 측이 TCP 헤더의 Window 필드로 통보하는 **가용 버퍼 크기(rwnd)에 따라 송신 윈도우를 동적으로 조절하는 종단 간 흐름 제어 기제**
- 배경/필요성: 고속 송신자가 저속 수신자의 처리 용량을 초과하여 전송할 때 발생하는 **수신 버퍼 고갈, 패킷 드롭 및 불필요한 전체 재전송 폭주 해결 불가**

#### 한줄 요약
- rwnd와 cwnd의 최솟값을 기준으로 슬라이딩 윈도우를 전진시키며 수신 버퍼 오버플로우를 차단한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Effective Window (유효 윈도우)**: 송신 측이 수신자 여유(rwnd)와 네트워크 혼잡도(cwnd) 중 최솟값을 취해 결정하는 실제 송신 허용량 ($\min(\text{rwnd}, \text{cwnd})$).
- **Sliding Window Algorithm**: ACK가 도착할 때마다 윈도우의 좌측 경계를 우측으로 전진시켜 추가 데이터를 연속 송출하는 알고리즘.

</details>

- 송신 측은 수신자 여유(**rwnd**)와 혼잡도(**cwnd**) 중 **최솟값인 $\min(\text{rwnd}, \text{cwnd})$**을 상한으로 송신
- **슬라이딩 윈도우(Sliding Window)**를 통해 매 패킷마다 개별 ACK 대기 없이 연속 파이프라인 전송
- 수신 버퍼 가용 공간에 따라 윈도우 크기를 동적으로 축소/확장 통보하는 **피드백 제어 루프**

#### 한줄 요약
- rwnd/cwnd 상한 제어, 슬라이딩 윈도우 파이프라인, 피드백 버퍼 동기화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Persist Timer (지속 타이머)**: 제로 윈도우(rwnd=0) 상황에서 수신 측의 윈도우 갱신 ACK 유실 시 발생할 수 있는 교착 상태(Deadlock)를 방지하는 타이머.
- **Window Scale Option (RFC 7323)**: 16비트(64KB) 기본 윈도우 헤더 한계를 극복하여 최대 1GB까지 윈도우 버퍼를 확장하는 TCP 옵션.

</details>

```text
[TCP 송신 윈도우 슬라이딩 구조 및 버퍼 상태]
|-- 1. Sent & ACKed (전송 완료 및 수신 확인 완료 -> 소켓 버퍼에서 해제)
|-- 2. Sent & UnACKed (전송 완료되었으나 아직 ACK 미수신 -> 재전송 대기)
|-- 3. Usable Window (미전송 상태이나 rwnd 허용 범위 내 -> 즉시 전송 가능)
`-- 4. Not Usable (rwnd 초과 영역 -> ACK 수신으로 윈도우 슬라이딩 전까지 전송 불가)
```

선의 의미: 계층 및 수신자로부터 ACK가 도착하면 1번 영역이 확대되며 윈도우가 우측으로 이동(Sliding)하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **송신 윈도우 관리기** | 광고된 rwnd 크기 내에서 **미확인 데이터를 파이프라인으로 전송하고 ACK 수신 시 슬라이딩** | 송신 측 제어 |
| **수신 윈도우 관리기** | 수신 버퍼에서 애플리케이션이 데이터를 인출한 후 **가용 공간(rwnd)을 재계산하여 통보** | 수신 측 피드백 |
| **지속 타이머 (Persist)** | rwnd=0 도달 시 교착 상태를 방지하기 위해 **주기적으로 1바이트 윈도우 프로브(Probe) 전송** | 데드락 방어 |
| **윈도우 확장 옵션 (WS)** | 기본 16비트(64KB) 헤더 한계를 극복하여 **최대 1GB까지 윈도우 크기를 확장(RFC 7323)** | BDP 극복 옵션 |

#### 한줄 요약
- 송수신 윈도우 관리기, 지속 타이머, 윈도우 스케일 옵션이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Window Probe (윈도우 탐사 패킷)**: 수신자가 rwnd=0을 알린 후 지속 타이머가 만료될 때마다 수신자의 윈도우 상태를 확인하기 위해 보내는 1바이트짜리 패킷.

</details>

```text
TCP 슬라이딩 윈도우 흐름 제어 파이프라인
        │
   1. [수신 버퍼 측정] 수신 측이 가용 공간을 계산하여 TCP ACK 헤더에 `rwnd=64KB` 통보
        │
   2. [유효 윈도우 산출] 송신 측이 $\min(\text{rwnd}, \text{cwnd})$ 계산
   ┌────┴───────────────────────────┐
  rwnd > 0 (정상 가용 공간)         rwnd = 0 (제로 윈도우 도달)
   │                                 │
3A. [슬라이딩 윈도우 연속 송출]      3B. [지속 타이머 가동]
   ACK 대기 없이 64KB 연속 전송          주기적 1바이트 Window Probe 발송
   │                                 │
   ▼                                 ▼
4A. [ACK 수신 및 윈도우 전진]        4B. [윈도우 갱신 ACK 수신]
   수신 확인 바이트만큼 우측 전진        정상 rwnd 확인 후 슬라이딩 전송 재개
```

#### 한줄 요약
- rwnd 통보 → 유효 윈도우 산출 → 슬라이딩 연속 전송 → ACK 수신 시 전진 / 제로 윈도우 시 프로브 전송으로 제어한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Stop-and-Wait** vs **Sliding Window**: 단일 패킷 전송 후 대기하는 방식과 윈도우 크기만큼 연속 전송하는 파이프라인 방식.

</details>

| 비교 항목 | 슬라이딩 윈도우 (Sliding Window) | 정지-대기 (Stop-and-Wait) |
|:---|:---|:---|
| **패킷 전송 방식** | 허용된 윈도우(rwnd) 내에서 **ACK 대기 없이 연속 전송**| 단 1개의 세그먼트 전송 후 **반드시 ACK 수신 대기** |
| **대역폭 활용률(BDP)**| **극대화 (네트워크 파이프라인 연속 활용)** | **극히 낮음 (RTT 동안 회선이 유휴 상태로 방치)** |
| **구현 복잡도** | 시퀀스 번호 추적, 재전송 큐, 버퍼 슬라이딩 관리 필요 | 단순 타이머 기반으로 구조가 매우 단순 |
| **표준 적용 영역** | **현대 고속 TCP/IP 네트워크의 표준 흐름 제어** | TFTP, 소형 센서 통신 등 제한적 임베디드 |

#### 한줄 요약
- 정지-대기 방식의 심각한 대역폭 낭비를 슬라이딩 윈도우의 연속 파이프라인 전송으로 극복한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **BDP (Bandwidth-Delay Product)**: 대역폭($\text{bps}$)과 왕복 시간($\text{RTT}$)의 곱으로, 파이프라인을 최대로 채우기 위해 요구되는 최적 윈도우 크기 ($\text{BDP} = \text{Bandwidth} \times \text{RTT}$).
- **Silly Window Syndrome (SWS)**: 수신 버퍼가 1바이트 비워질 때마다 작은 윈도우를 광고하고 송신자도 작은 패킷을 전송하여 헤더 오버헤드가 폭증하는 비효율 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수신 측 윈도우 갱신 ACK 유실로 인한 영구 송신 대기(Deadlock) | 송신 측 커널의 **`지속 타이머(Persist Timer) 및 Window Probe` 활성화** | 윈도우 상태 자동 재동기화 및 데드락 해소 |
| 10Gbps 이상 초고속망에서 기본 64KB 윈도우 한계로 인한 속도 저하 | TCP 3-Way Handshake 시 **`Window Scale (RFC 7323)` 옵션 협상** | BDP를 충족하는 최대 1GB 윈도우로 전송률 극대화 |
| 작은 바이트 전송으로 헤더 오버헤드가 급증하는 **SWS 현상** | **수신 측 `Clark 알고리즘` 및 송신 측 `Nagle 알고리즘` 결합** | 미세 패킷 전송 억제 및 대역폭 효율 최적화 |
| 소켓 수신 버퍼 부족으로 인한 TCP 패킷 드롭 및 재전송 | **리눅스 커널 `tcp_rmem / tcp_wmem` 소켓 오토튜닝 활성화** | 가용 메모리 기반 동적 버퍼 할당 및 처리량 보장 |

#### 한줄 요약
- 지속 타이머로 데드락 방지, Window Scale로 BDP 충족, Clark/Nagle로 SWS 방어, 커널 오토튜닝을 적용한다.

## Ⅶ. 결론

- 고속 광대역 네트워크 환경에서 수신 버퍼 오버플로우를 원천 차단하고 회선 처리량을 극대화하기 위해 **슬라이딩 윈도우 알고리즘과 Window Scale(RFC 7323) 옵션을 전사 표준 적용**하고, **지속 타이머와 Clark/Nagle SWS 방어 알고리즘 및 커널 버퍼 오토튜닝**을 결합하여 고성능·무결점 전송 인프라 완성

#### 한줄 요약
- TCP 흐름 제어는 슬라이딩 윈도우와 rwnd 피드백을 통해 수신 버퍼를 보호하며, Window Scale과 지속 타이머를 통해 고속 전송을 보장하는 핵심 전송 계층 기술이다.
