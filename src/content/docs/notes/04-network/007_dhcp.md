  priority_note: "설명형: DORA•Lease �## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **동적 호스트 구성 프로토콜(Dynamic Host Configuration Protocol, DHCP)**: 네트워크에 접속하는 단말에 IP 주소, 서브넷 마스크, 기본 게이트웨이 등의 설정을 자동 임대하는 응용 계층 프로토콜.
- **인터넷 프로토콜(Internet Protocol, IP)**: 패킷 송수신 노드의 논리적 주소 지정 및 경로 선택을 수행하는 라우팅 프로토콜.

</details>

- 정의/개념: 서버가 클라이언트에 **인터넷 프로토콜(Internet Protocol, IP)** 주소 및 네트워크 옵션을 정해진 기간 동안 자동 동적 임대하는 **DHCP(Dynamic Host Configuration Protocol)** 프로토콜.
- 배경/필요성: 수동 IP 설정에 따른 주소 중복, 설정 오류, 관리 비용 증가 및 주소 회수 누락 문제의 해소.

#### 한줄 요약

- 단말이 네트워크에 들어오면 서버가 빈 주소와 이용 규칙을 정해진 기간 동안 빌려준다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 풀(Address Pool)**: DHCP 서버가 단말들에 할당 가능하도록 보유하고 있는 유효 IP 주소 범위.
- **바인딩(Binding)**: DHCP 서버가 할당한 IP 주소, 클라이언트 MAC 주소, 임대 시간(Lease Time) 간의 매핑 기록.
- **DHCP 릴레이 에이전트(DHCP Relay Agent)**: 브로드캐스트 패킷 전달이 제한되는 서브넷 경계 라우터에서 DHCP 패킷을 유니캐스트로 변환하여 중앙 서버로 전달하는 장치.

</details>

- **주소 풀(Address Pool)** 및 **바인딩(Binding)** 관리를 통한 IP 주소 중복 할당 방지.
- 초기 네트워크 진입 시 브로드캐스트 패킷 기반 자동 설정 지원.
- **DHCP 릴레이 에이전트(DHCP Relay Agent)**를 활용한 서브넷 간 통합 DHCP 서버 운영 지원.

#### 한줄 요약

- 단말은 먼저 빌려줄 서버를 찾고 주소를 받은 뒤 만료 전에 연장을 요청한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **DHCP 클라이언트(DHCP Client)**: 네트워크 접속 시 DHCP 서버로부터 IP 주소 및 시스템 옵션을 수신받아 적용하는 단말.
- **DHCP 옵션(DHCP Option)**: IP 주소 이외에 서브넷 마스크, 기본 게이트웨이, DNS 서버, NTP 서버 등의 부가 설정값을 전달하는 가변 길이 필드.
- **도메인 이름 시스템(Domain Name System, DNS)**: 사람이 읽기 쉬운 도메인 이름을 IP 주소로 변환해 주는 분산 데이터베이스 시스템.

</details>

```text
DHCP 클라이언트
└── DHCP 릴레이
    └── DHCP 서버
        └── 주소•바인딩 저장소
```

선의 의미: 클라이언트의 IP 요청, 릴레이의 L3 경계 패킷 전달, 서버의 주소/옵션 바인딩 저장소 간의 상호작용 체계 표시.

| 구성요소 | 책임 |
|:---|:---|
| DHCP 클라이언트 | **DHCP 클라이언트(DHCP Client)**의 주소 탐색•임대 요청 |
| DHCP 릴레이 | **DHCP 릴레이 에이전트(DHCP Relay Agent)**의 서브넷 간 요청•응답 중계 |
| DHCP 서버 | **주소 풀(Address Pool)**과 **DHCP 옵션(DHCP Option)**에 따른 임대 승인•**DNS** 설정 전달 |
| 주소•바인딩 저장소 | 가용 주소와 단말•주소•만료 시각의 **바인딩(Binding)** 관리 |

#### 한줄 요약

- 지점 단말의 요청을 릴레이가 중앙 서버에 전하면 서버가 빈 주소와 설정을 찾아 돌려준다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **DORA 절차(DORA Process)**: DHCP 클라이언트와 서버 간 주소 임대를 위해 수행하는 Discover, Offer, Request, Acknowledge 4단계 핸드셰이크.
- **DHCPDISCOVER**: 클라이언트가 네트워크 상의 DHCP 서버를 탐색하기 위해 발송하는 브로드캐스트 메시지.
- **DHCPOFFER**: DHCP 서버가 클라이언트에게 할당 가능한 IP 주소 및 임대 조건을 제안하는 메시지.
- **DHCPREQUEST**: 클라이언트가 제안받은 서버의 IP 주소 할당을 최종 요청하는 메시지.
- **DHCPACK**: 서버가 클라이언트의 임대 요청을 최종 승인하고 설정값을 전달하는 응답 메시지.
- **브로드캐스트(Broadcast)**: 동일 브로드캐스트 도메인 내 전체 노드로 데이터를 전송하는 방식.

</details>

```text
DHCP 클라이언트
      |
      v
1. DHCPDISCOVER
      |
      `-- 브로드캐스트 ---- DHCP 서버 후보 탐색
      |
      v
2. DHCPOFFER
      |
      `-- 주소•옵션•임대 시간 후보
      |
      v
3. DHCPREQUEST
      |
      `-- 선택 서버•주소 요청
                    |
                    v
             임대 바인딩 저장
                    |
                    v
               4. DHCPACK
                    |
                    `-- 주소•옵션 적용
```

### 동작 원리

**DORA 절차(DORA Process)**를 통한 4단계 주소 임대 수행:

1. **DHCPDISCOVER**: **브로드캐스트(Broadcast)** 기반 가용 DHCP 서버 탐색.
2. **DHCPOFFER**: 가용 IP 주소 및 옵션 제안 메시지 송신.
3. **DHCPREQUEST**: 특정 서버 선택 및 IP 할당 요청 메시지 송신.
4. **DHCPACK**: 임대 **바인딩(Binding)** 저장 및 최종 승인 옵션 전달.

#### 한줄 요약

- 단말이 빈 주소를 문의하면 서버가 후보를 내고 단말이 하나를 요청한 뒤 서버가 임대를 확정한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **동적 임대(Dynamic Lease)**: 단말 접속 시 주소를 임시 배정하고 해제 시 회수하여 주소 풀 자원을 효율화하는 방식.
- **수동 고정 할당(Manual Static Allocation)**: 특수 장비의 MAC 주소와 특정 IP 주소를 1:1로 매핑하여 고정 할당하는 방식.

</details>

| 주소 구성 방식 | **동적 임대** | **수동 설정** |
|:---|:---|:---|
| 적용 기준 | 접속•이탈이 잦은 다수 단말 | 주소가 고정된 소수 기반 장비 |
| 핵심 특징 | 서버가 주소•옵션을 자동 임대 | 관리자가 장치마다 고정 입력 |
| 한계 | 가짜 서버•주소 풀 고갈 | 중복 주소•설정 누락 |

> 요약: 변동 단말 대상의 동적 임대 방식과 서버/인프라 대상의 static 수동/고정 할당 방식 간 비교.

#### 한줄 요약

- 자주 드나드는 단말은 빈 번호를 자동으로 빌리고 늘 같은 장비는 관리자가 번호를 고정한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **DHCP 스누핑(DHCP Snooping)**: L2 스위치에서 비인가 DHCP 서버의 주소 할당을 차단하고 신뢰 포트 기반으로 바인딩 테이블을 생성하는 L2 보안 기능.
- **릴레이 에이전트 정보 옵션(Relay Agent Information Option, Option 82)**: DHCP 릴레이 에이전트가 패킷에 클라이언트의 물리적 포트 및 VLAN 정보를 삽입하는 DHCP 옵션.
- **T1 타이머(Renewal Time, T1)**: 임대 기간의 50% 시점에서 클라이언트가 기존 서버에 임대 연장을 유니캐스트로 요청하는 시점.
- **T2 타이머(Rebinding Time, T2)**: 임대 기간의 87.5% 시점에서 클라이언트가 모든 DHCP 서버에 재결합을 브로드캐스트로 요청하는 시점.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동시 접속 단말이 주소 풀을 초과 | 접속량•체류시간 기반 **주소 풀(Address Pool)** 산정 | 주소 할당 실패 감소 |
| 비인가 서버가 악성 옵션을 응답 | **DHCP 스누핑(DHCP Snooping)** 신뢰 포트 지정 | 가짜 서버 응답 차단 |
| 릴레이가 접속 위치 정보를 위조 | **Option 82**와 신뢰 릴레이 검증 | 할당 위치 신뢰성 확보 |
| 장기 임대로 미사용 주소가 묶임 | 이동성별 임대 시간•**T1**•**T2** 차등 | 주소 회수 시간 단축 |

#### 한줄 요약

- 스위치는 관리자가 지정한 포트에서 온 주소 배부 응답만 단말에 전달한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **임대 시간(Lease Time)**: DHCP 클라이언트가 서버 갱신 없이 할당받은 IP를 정당하게 사용할 수 있는 유효 기간.
- **임대 정책 결정(Lease Policy Formulation)**: 단말 유형, 체류 패턴 및 네트워크 자원 상태를 바탕으로 최적의 IP 임대 기한과 풀 범위를 산정하는 프로세스.

</details>

- **임대 정책 결정(Lease Policy Formulation)**에 기초한 트래픽 패턴 기반 주소 풀 규모 산정 및 **임대 시간(Lease Time)** 최적화 수행.

- 동시에 접속할 단말 수와 체류시간을 알아야 주소 풀과 임대시간을 정할 수 있다.

### 동작 원리

**DORA**는 다음 네 메시지로 임대를 확정한다.

1. **DHCPDISCOVER**: **브로드캐스트**로 사용 가능한 서버를 탐색한다.

3. **DHCPREQUEST**: 선택한 서버와 주소의 임대를 요청한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **DHCP 스누핑**: 스위치가 신뢰 포트의 서버 응답만 허용하고 주소•단말•포트 바인딩을 기록하는 보안 기능이다.
- **릴레이 에이전트 정보 옵션(Relay Agent Information Option, Option 82)**: 릴레이가 단말의 접속 회선과 장치 정보를 DHCP 서버에 전달하는 옵션이다.
- **T1(Renewal Time Value)**: 단말이 기존 서버에 임대 갱신을 요청하는 시점이다.
- **T2(Rebinding Time Value)**: 단말이 모든 서버에 임대 재결합을 요청하는 시점이다.

</details>

|:---|:---|:---|

| 비인가 서버가 악성 옵션을 응답 | **DHCP 스누핑** 신뢰 포트 지정 | 가짜 서버 응답 차단 |
| 릴레이가 접속 위치 정보를 위조 | **Option 82**와 신뢰 릴레이 검증 | 할당 위치 신뢰성 확보 |
| 장기 임대로 미사용 주소가 묶임 | 이동성별 임대 시간•**T1**•**T2** 차등 | 주소 회수 시간 단축 |

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **임대 시간**: 단말이 갱신 없이 주소를 사용할 수 있는 기간이다.
- **임대 정책 결정**: 동시 접속 단말 수와 체류시간을 기준으로 주소 풀 크기와 임대 시간을 정하는 판단이다.

</details>

- **임대 정책 결정**은 동시 접속•체류시간을 기준으로 주소 풀과 **임대 시간**을 설정하는 판단이다.

#### 한줄 요약

- 동시에 접속할 단말 수와 체류시간을 알아야 주소 풀과 임대시간을 정할 수 있다.
