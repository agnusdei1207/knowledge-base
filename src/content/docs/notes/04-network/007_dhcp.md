## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DHCP(Dynamic Host Configuration Protocol)**: 회사에 출근해서 랜선만 꽂으면, 서버가 알아서 남는 IP 주소를 빌려주고 설정까지 다 해주는 응용 계층의 프로토콜이다.
- **IP 주소(IP Address)**: 컴퓨터가 인터넷을 하기 위해 반드시 필요한 도로명 주소(논리 주소)로, 겹치면 통신이 마비된다.

</details>

- 정의: 네트워크 단말에 IP 주소, 게이트웨이, DNS 등 통신 설정을 알아서 자동 임대해 주는 **동적 구성 프로토콜**
- 배경: 수많은 PC를 사람이 일일이 수동 설정하면 **IP 충돌이 나고, 나간 사람의 주소 회수가 불가능했기 때문** #### 한줄 요약

- 랜선만 꽂으면 복잡한 IP 세팅을 서버가 알아서 척척 해주고 빌려주는 천사 같은 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 풀(Address Pool)**: "여기서부터 저기까지 남는 IP 빌려줄게" 하고 서버가 쥐고 있는 주소 대여 금고이다.
- **바인딩(Binding)**: 서버가 "이 IP는 이 MAC 주소(랜카드) 가진 놈한테 언제까지 빌려줬음" 하고 1:1로 묶어서 장부에 적어두는 상태 정보이다.
- **DHCP 릴레이 에이전트(DHCP Relay Agent)**: 브로드캐스트(동네방네 소리치는) 요청이 공유기를 못 넘어가니까, "내가 옆 동네 서버한테 대신 전해줄게" 하고 뛰쳐나가는 심부름꾼이다.

</details>

- **주소 풀** 및 **바인딩** 장부를 통한 동적 IP 자원 관리로 IP 중복 할당 원천 방지 및 회수 자동화.
- UDP 프로토콜 기반의 4단계 셰이크 핸드(DORA)로 컴퓨터를 켜자마자 바로 통신이 가능하게 지원.
- 부서(서브넷)마다 비싼 서버를 둘 필요 없이, **DHCP 릴레이 에이전트** 기반 중앙 서버에서 통합 관리.

#### 한줄 요약

- 주소 풀 장부로 IP 충돌을 막고, 릴레이 에이전트를 써서 본사 서버 하나로 전 지사를 관리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DHCP 서버(DHCP Server)**: 주소 풀과 바인딩 장부를 들고 다니며 단말의 요청을 받아 IP를 빌려주고 관리하는 중앙 관리자(UDP 67)이다.
- **DHCP 클라이언트(DHCP Client)**: 부팅하자마자 "저 IP 좀 주세요!" 하고 동네방네 소리치는 단말 장비(UDP 68)이다.
- **DORA 절차(DORA Procedures)**: 클라이언트와 서버가 "계세요?(Discover) - 이거 쓸래?(Offer) - 네 쓸게요(Request) - 그래 써라(ACK)" 하며 4단계로 IP를 임대하는 메커니즘이다.

</details>

```text
[ DHCP DORA 직관적 비교 아키텍처 ]

[ PC (클라이언트, UDP 68) ]                          [ 서버 (UDP 67) ]
           │                                                │
           ├─ 1. Discover ("IP 주실 분 계세요??", 방송) ──▶ │
           │                                                │
           │ ◀── 2. Offer ("192.168.0.5 쓸래?", 제안) ──────┤
           │                                                │
           ├─ 3. Request ("네 0.5번 제가 쓸게요!", 확정) ─▶ │
           │                                                │
           │ ◀── 4. ACK ("ㅇㅋ 계약 완료. 써라", 승인) ─────┤
```

| 구성요소 | 책임 | 전송 방식 및 포트 |
|:---|:---|:---|
| **DHCP 서버** | IP 금고(주소 풀)를 관리하고, DNS나 게이트웨이 옵션까지 싹 다 세팅해서 쏴줌 | UDP **67번** 수신 |
| **DHCP 클라이언트** | 부팅하면 브로드캐스트로 소리쳐서 IP를 구걸하고, 시간 지나면 임대 연장함 | UDP **68번** 사용 |
| **DORA 절차** | 발견(D) $\to$ 제안(O) $\to$ 요청(R) $\to$ 승인(A)의 4단계 눈치 게임 | 브로드캐스트/유니캐스트 혼용 |
| **DHCP 옵션** | IP만 주면 섭섭하니까 옵션 3(공유기), 옵션 6(DNS) 같은 필수 정보를 덤으로 줌 | 파라미터 확장 헤더 |

#### 한줄 요약

- 67번 포트로 듣는 서버와 68번 포트로 구걸하는 클라이언트가 DORA 4단계로 거래를 튼다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DHCP 탐색(DHCP Discover)**: PC를 켜자마자 서버가 어딨는지 몰라서 "IP 줄 사람!" 하고 브로드캐스트로 냅다 소리치는 메시지이다.
- **DHCP 제안(DHCP Offer)**: 동네방네 소리를 들은 서버들이 "나한테 IP 남는데 이거 쓸래?" 하고 조건(IP, 대여 시간)을 제시하는 메시지이다.
- **DHCP 요청(DHCP Request)**: PC가 여러 제안 중 하나를 픽해서 "A 서버님 거 쓸게요!" 하고 확정 도장을 찍는 메시지이다.
- **DHCP 승인(DHCP ACK)**: 최종 선택받은 서버가 장부(바인딩)에 기록하고 "ㅇㅋ 이거 진짜 니 거임" 하고 최종 사용 허가를 내리는 메시지이다.

</details>

```text
[ IP 임대 및 자동 갱신 십자포화 흐름 ]
┌──────────────────────────────┐
│ 0. PC 부팅 (IP 없음)         │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. [Discover] 서버 찾기      │
│ (나한테 IP 줄 사람 소리침)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [Offer] IP 제안받기       │
│ (서버들이 192.168.0.5 던져줌)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [Request] 사용 요청       │
│ (제안받은 0.5번 제가 쓸게요!)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [ACK] 임대 확정           │
│ (장부 적고, 타이머 50% 가동) │
└──────────────────────────────┘
```

### 동작 원리

1. DHCP 탐색: 클라이언트가 서버를 찾기 위해 브로드캐스트로 소리침.
2. DHCP 제안: 서버가 남는 IP와 대여 조건을 클라이언트에게 제시함.
3. DHCP 요청: 클라이언트가 제시된 IP를 쓰겠다고 정식 요청(다른 서버 제안은 거절 처리).
4. DHCP 승인: 서버가 바인딩 장부에 기록하고 IP 사용을 최종 승인함.
5. 임대 갱신: 대여 시간의 절반(T1)이 지나면 클라이언트가 알아서 연장 요청을 쏨.

#### 한줄 요약

- 찾고, 제안받고, 찍고, 허락받는 DORA 4박자로 IP를 빌려 쓰고 시간 지나면 알아서 연장한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **동적 할당(Dynamic Allocation)**: 커피숍 와이파이처럼, 2시간만 빌려주고 손님 나가면 바로 회수해서 딴 사람 주는 주소 돌려막기(표준 방식)이다.
- **수동 할당(Static Binding)**: 사내 프린터나 서버처럼 IP가 바뀌면 대규모 네트워크 장애가 나는 장비에게, "이 MAC 주소엔 무조건 이 IP만 줘라" 하고 못 박아두는 1:1 고정 매핑이다.

</details>

| 할당 방식 | **동적 할당 (표준 돌려막기)** | **수동/고정 할당 (Static Binding)** |
|:---|:---|:---|
| 핵심 개념 | 임대 시간(Lease Time) 걸어두고 시간 지나면 **가차 없이 회수함** | 특정 MAC 주소가 보이면 무조건 **미리 정해둔 고정 IP만 줌** |
| 주 활용 대상 | 직원 PC, 모바일 기기, 손님용 Wi-Fi | IP 바뀌면 다 죽는 **서버, 네트워크 프린터, 스위치** |
| 자원 효율성 | 최상 (IP 낭비 없이 알뜰하게 재활용함) | 보통 (IP를 계속 점유해서 낭비될 수 있음) |

#### 한줄 요약

- 핸드폰엔 동적 할당으로 빡세게 돌리고, 서버나 프린터는 수동으로 꽉 묶어둔다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DHCP 스푸핑(DHCP Spoofing)**: 해커가 몰래 싸구려 공유기를 꽂아놓고 "내가 진짜 서버야!" 하면서 가짜 IP와 가짜 게이트웨이를 뿌려 패킷을 훔쳐보는 악질 공격이다.
- **DHCP 스누핑(DHCP Snooping)**: 스위치가 중간에서 패킷을 까보고, "네트워크팀이 허락한 찐 포트(Trusted Port)에서 나온 DHCP 패킷만 통과시켜라" 하고 차단하는 방패 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 직원이 몰래 꽂은 공유기가 가짜 IP를 뿌려 **사내망이 마비됨 (Rogue)** | 스위치에 찐 서버 포트만 믿는 **DHCP 스누핑(DHCP Snooping)** 적용 | 비인가 가짜 Offer/ACK 패킷 원천 차단 |
| 좀비 PC가 가짜 MAC으로 구걸 패킷을 만 번 쏴서 **IP 풀 고갈 공격** | 스위치 포트별 학습 **MAC 개수 제한 및 패킷 속도(Rate) 제한** | IP 풀 고갈 예방 및 DOS 방지 |
| 라우터가 브로드캐스트를 막아버려서 **옆 부서가 IP를 못 받음** | 라우터에 유니캐스트로 대신 쏴주는 **DHCP 릴레이 에이전트** 설정 | 지사/부서별 통합 중앙 DHCP 서비스 구현 |

#### 한줄 요약

- 가짜 서버는 스누핑으로 쳐내고, 부서 간 막힌 벽은 릴레이 에이전트로 뚫어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **임대 기간 최적화(Lease Time Optimization)**: 손님이 휙휙 바뀌는 카페 와이파이는 임대 시간을 짧게 주고, 직원 PC는 길게 줘서 IP 고갈을 막는 눈치 빠른 정책이다.

</details>

- **임대 기간 최적화** 원칙에 따라, 단말 이동률에 맞춰 임대 시간을 조정하고 위조를 막는 **DHCP 스누핑** 결합하는 기조 확립함

#### 한줄 요약

- 카페 와이파이는 임대 시간을 짧게 끊고, 가짜 서버가 설치는 걸 스누핑으로 철통같이 막아라.
