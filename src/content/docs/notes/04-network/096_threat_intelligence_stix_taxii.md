## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CTI (사이버 위협 인텔리전스)**: 경찰청 수배자 명단처럼, 공격자의 IP, 사용한 악성코드 해시값, 해킹 기법을 묶어서 보안 장비가 방어에 써먹을 수 있게 만든 고가치 정보(Intelligence)다.
- **STIX (구조화된 위협 정보 표현)**: 해킹 정보(CTI)를 사람이 읽는 PDF나 엑셀로 쓰지 말고, 보안 장비(기계)가 바로 읽고 룰(Rule)에 박을 수 있도록 만든 만국 공통 '문법/양식'이다.
- **TAXII (위협 정보 자동 교환)**: STIX 언어로 만들어진 수배자 명단을 여러 회사나 이종 보안 장비들끼리 안전하고 빠르게 주고받을 수 있게 만든 전용 '메시지 전송 프로토콜'이다.

</details>

- 정의: **CTI 표준 체계** 기반 해커의 공격 정보를 기계가 읽을 수 있는 언어(**STIX**)로 구조화하고, 이를 조직과 보안 장비 간에 자동으로 배달(**TAXII**)하는 위협 방어 생태계다.
- 배경: 예전엔 보안 회사가 PDF 리포트로 해킹 정보를 주면 관제 요원이 그걸 읽고 방화벽에 수동으로 입력해야 하는 **비정형 위협 정보 자동 연계 한계 때문에 골든타임을 다 날려 먹었다.** #### 한줄 요약

- 수배자 얼굴과 죄목을 기계가 읽게 코딩(STIX)하고, 그걸 전 세계 방화벽에 1초 만에 배달(TAXII)하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **위협 지표 (IoC, Indicator of Compromise)**: "이 IP 주소랑 이 파일 해시값이 보이면 100% 해킹 당한 거다"라고 찍어주는 증거물이다.
- **TLP (Traffic Light Protocol)**: 위협 정보를 받았을 때, Red(나만 봄), Amber(우리 조직만), Green(협력사 공유), White(전체 공개) 등 색깔로 공유 범위를 엄격하게 제한하는 규약이다.

</details>

- **언어 (STIX 객체)**: 단순 IP 하나 달랑 던지는 게 아니라, [공격자 조직 ↔ 사용 기법 ↔ 위협 지표] 간의 관계를 거미줄처럼 엮어서 기계가 맥락을 이해하게 만든다.
- **안전 패킷 데이터 (TAXII 컬렉션)**: 권한과 공유 등급(TLP)에 맞춰서 허락된 조직과 도구에만 정보를 게시하고 자동 배달한다.
- **집행 통제**: 유통기한(유효 기간)이 지난 지표는 방화벽 룰에서 자동으로 빼버려서 애먼 사람 잡는 오탐을 줄인다.

#### 한줄 요약

- IP 주소만 던져주는 게 아니라, "이건 북한 소행이고, 기밀이고, 한 달만 유효함"이라는 꼬리표를 딱 붙여서 쏜다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **위협 검증•보강기**: 남이 준 해킹 IP라도 무지성으로 방화벽에 막지 않고, 진짜 위험한지 신뢰도와 유효기간을 까보는 까다로운 문지기다.

</details>

```text
[ CTI 위협 정보 공유 및 배포 구조 ]

[ 외부 보안 기관 / 협력사 ] ── (해커 IP랑 악성코드 정보 제보해 줌)
      │
      ▼
[ 1. 위협 검증•보강기 ] ── (진짜인지 체크하고 유통기한 세팅)
      │
      ▼
[ 2. STIX 객체 저장소 ] ── (표준 문법(STIX)으로 변환해서 DB에 안전하게 격리 보관음)
      │
      ▼ (TAXII 규약 통신)
[ 3. TAXII 교환 서버 ] ── (배포 권한 확인. Red 등급은 빼고 Green만 발송 준비)
      │
      ▼ (자동 배달)
[ 4. 보안 도구 소비자 ] ── (SIEM, 방화벽: 오케이, 받은 IP 바로 차단 룰에 박을게!)
      │
      └─▶ [ 5. 품질 환류기 ] ── (방화벽: 야, 네가 준 거 오탐이더라 ㅡㅡ 즉각 피드백)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **위협 검증•보강기** | 쓰레기 정보 거르고 **찐 해킹 정보인지 체크하는 입구** | Validator |
| **STIX 객체 저장소** | 온갖 포맷의 제보를 **STIX 언어로 번역해서 보관하는 창고** | Repository |
| **TAXII 교환 서버** | 권한(TLP) 확인하고 **받을 놈한테만 STIX 뿌려주는 패킷 라우팅 엔진** | TAXII Server |
| **보안 도구 소비자** | 배달받은 지표(IoC)를 **방화벽이나 SIEM에 바로 쑤셔 넣는 장비들** | Consumer |
| **품질 환류기** | 적용해 보니 오탐이면 **즉시 신뢰도 까내리고 룰에서 폐기하는 브레이크** | Feedback |

#### 한줄 요약

- 정보 받기 $\to$ STIX로 번역 $\to$ TAXII로 배달 $\to$ 방화벽 차단 $\to$ 잘못되면 환류(수정)의 흐름이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **증분 동기화**: 백날 천날 똑같은 수배자 명단 수십만 개를 통째로 주지 말고, 저번 이후로 새로 추가되거나 만료된(변경된) 내용만 효율적으로 주고받는 거다.
- **품질 환류 (Feedback)**: CTI 정보가 영원히 진리는 아니므로, 차단해 봤더니 정상 트래픽(오탐)이면 즉시 그 지표를 쓰레기통에 넣는 사후 검증 단계다.

</details>

```text
[ STIX/TAXII 위협 정보 라이프사이클 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [위협 근거 수집 및 검증]  │
│ (OSINT나 협력사에서 정보 긁어옴. 신뢰도 체크)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [STIX 객체 및 관계 등록]  │
│ (IP ↔ 해커조직 ↔ 악성코드 관계를 STIX 문법으로 그림 그림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [TAXII 컬렉션 객체 제공]  │
│ (TLP 등급 매겨서 공유 채널(게시판)에 배포 준비 완료)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [증분 객체 요청 및 보안 장비 적용]
│ (방화벽: 어제 이후로 새로 뜬 수배자 명단만 줘. 바로 차단함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [품질 결과 환류 (피드백)] │
│ (시간 지나서 만료되거나 오탐 나면 즉시 신뢰도 깎고 회수함)
└──────────────────────────────┘
```

### 동작 원리

1. 정보 검증: 출처 불분명한 찌라시는 버리고 믿을 만한 지표만 검증해서 가져옴.
2. STIX 등록: 지표 간의 맥락(누가 어떤 수법을 썼는지)을 엮어 STIX 객체로 만듦.
3. 컬렉션 제공: 아무나 못 보게 TLP(색상) 권한 박아서 TAXII 서버에 올려둠.
4. 배포 및 적용: 각 장비들이 바뀐 내용(증분)만 쏙쏙 빼가서 실시간 차단 룰로 써먹음.
5. 환류 및 폐기: 유효기간 끝난 좀비 IP나 오탐 나는 지표는 즉각 회수해서 버림.

#### 한줄 요약

- 검증하고 $\to$ 문법 맞추고 $\to$ 권한 맞춰서 $\to$ 배달하고 $\to$ 썩은 건 솎아낸다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

| 구분 | **STIX (정보의 표현 언어)** | **TAXII (정보의 전송 규약)** |
|:---|:---|:---|
| 핵심 특징 | **수배자 얼굴과 죄목이 적힌 '수배 전단지 양식'** | **전단지를 경찰서마다 뿌리는 '우편 시스템(패킷 데이터)'** |
| 주력 임무 | 공격자, 기법, 위협 지표(IoC)의 **맥락과 관계를 기계가 읽게 코딩함** | 만들어진 STIX 데이터를 **조직과 도구 사이에서 권한에 맞게 교환함** |
| 기술 요소 | SDO(개체 객체), SRO(관계 객체), Indicator(지표) | Collection(채널 묶음), Channel, Polling/Push |
| 핵심 효과 | 보안 장비 제조사가 달라도 **동일한 문법으로 룰(Rule)을 찍어냄** | 이메일이나 PDF로 수동 전달하던 짓을 **API로 1초 만에 배포함** |

#### 한줄 요약

- 정보에 '무엇'을 적을지는 STIX가 정하고, 그걸 '어떻게' 배달할지는 TAXII가 책임진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스키마 검증/매핑**: STIX 문법이 아무리 예뻐도, 수신받는 구형 방화벽이 그걸 제대로 해석 못 하면 룰이 꼬이므로 중간에 통역 검증을 빡세게 하는 과정이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 5년 전 공격 IP를 지금도 차단해 **정상 손님 접속이 안 됨 (팀킬)** | 악성 IP 주인이 정상 서비스로 바뀌었는데 수배자 명단에서 안 지움 | STIX 규격 내 **'유효 기간(Valid Time)' 박고, 기한 지나면 자동 만료/삭제함** | 낡은 좀비 지표로 인한 무지성 정상 서비스 오차단 방지 |
| 나만 보려고 1억 주고 산 정보를 **협력사가 외부에 다 까발림** | 위협 정보의 기밀성과 공유 범위에 대한 통제 장치가 부재함 | STIX에 **TLP(색상 등급) 태그 달고, TAXII 권한으로 허락된 놈만 가져가게 통제함** | 고가치 인텔리전스 유출 방지 및 공유 생태계 신뢰(Trust) 확보 |
| STIX 줬는데 방화벽이 해석 못해 **탐지 룰 적용이 누락됨** | 기계(도구)가 STIX 언어를 자체 방화벽 규격으로 번역하다가 필드를 씹어먹음 | 보안 장비 수신단에 **'스키마 검증/매핑' 로직 빡세게 돌려서 변환 손실 막음** | 정보 누락 없이 100% 타격(차단 룰) 실행 보장 |

#### 한줄 요약

- 유통기한 지난 지표는 바로바로 버리고, 비싼 정보는 권한 쪼개서 주고, 장비가 말귀 못 알아먹지 않게 통역 잘해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **OASIS**: 국제적으로 쩌는 정보 교환 표준을 만드는 비영리 짱짱 기구다. 여기서 STIX랑 TAXII 표준을 관리한다.

</details>

- 비정형 위협 정보의 자동화 연계 한계를 완벽히 극복하기 위해, **OASIS STIX** 기반 위협 의미를 기계 언어로 구조화하고, **TAXII** 기반 권한별 초고속 교환 체계를 구축한 글로벌 CTI 생태계 기조 확립함

#### 한줄 요약

- CTI는 정보 많이 모으는 게 장땡이 아니다. 오탐 없고 싱싱한 지표(STIX)를 가장 빠르게 필요한 곳에 명시한(TAXII) 놈이 이기는 거다.
