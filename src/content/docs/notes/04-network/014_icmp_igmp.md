## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터넷 제어 메시지 프로토콜(ICMP)**: 패킷 데이터(IP 패킷)가 가다가 길 끊기거나 막히면 "야 거기 안 가져!" 하고 송신자한테 에러를 알려주는 보조 프로토콜이다.
- **인터넷 그룹 관리 프로토콜(IGMP)**: "나 이 방송 볼래!" 하고 손을 든 PC한테만 똑같은 방송(멀티캐스트)을 뿌려주려고 수신 그룹을 관리하는 프로토콜이다.
- **인터넷 프로토콜(IP)**: 일단 목적지로 냅다 던지고 보는 무책임한 L3 배달부다.

</details>

- 정의: L3 IP 전송의 에러를 보고하는 **ICMP** 및 멀티캐스트 방송 그룹을 통제하는 **IGMP**
- 배경: 냅다 던지고 끝인 IP 프로토콜만으로는 **전송 실패 원인을 파악하거나 특정 방송 수신자 그룹만 관리하는 게 불가능했기 때문** #### 한줄 요약

- 패킷 가다 죽으면 이유를 알려주는 게 ICMP고, 방송 볼 사람만 골라서 뿌려주는 게 IGMP다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ICMP 유형(Type) 및 코드(Code)**: "길이 막힘(Type 3)", 그중에서도 "패킷 데이터가 너무 커서 못 지나감(Code 4)"처럼 팩트를 콕 집어주는 에러 분류표다.
- **IGMP 질의(Query)**: 라우터가 "이 방송 아직 보는 사람 있냐?" 하고 주기적으로 찔러보는 확인 패킷이다.
- **IGMP 보고(Report)**: "나 이 채널 볼래!" 혹은 "나 아직 보고 있어!" 하고 PC가 손을 드는 가입/유지 패킷이다.
- **IGMP 탈퇴(Leave)**: "나 이제 안 볼래, 끊어" 하고 채널을 돌릴 때 빠르게 탈퇴를 통보하는 패킷이다.

</details>

- **ICMP 유형(Type)** 및 **코드(Code)** 를 조합하여 "왜 전송이 실패했는지" 구체적인 에러 원인 통보.
- **IGMP 질의(Query)**, **보고(Report)**, **탈퇴(Leave)** 3단계 메시지 상호 메시지 교환으로 서브넷 내 방송 가입자를 동적으로 관리.
- L2 스위치의 **IGMP 스누핑(IGMP Snooping)** 기능과 엮어서, 안 보는 놈한테는 방송 트래픽이 새어 나가지 않게 완전 차단.

#### 한줄 요약

- ICMP는 Type/Code로 에러 원인을 직관적 비교하고, IGMP는 질의/보고/탈퇴로 시청자를 관리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IGMP 스누핑(IGMP Snooping)**: L2 스위치가 라우터랑 PC 사이에 오가는 편지(Report)를 엿듣고 "아 1번 포트는 이거 보는구나" 하고 1:1로 꽂아주는 조율 기능이다.
- **IGMP 질의자(IGMP Querier)**: 동네 라우터 여러 대 중에 "누가 볼지 내가 물어볼게" 하고 대표로 나서는 질문 담당 라우터다.

</details>

```text
[ ICMP/IGMP 제어 피드백 직관적 비교 구조 ]

[ ICMP 에러 피드백 ]                [ IGMP 멀티캐스트 가입 ]

    (패킷 데이터가 너무 커서 못가!)          (이 방송 보는 사람?)
라우터 ─────────▶ 송신 PC         라우터(Querier) ──▶ 스위치
 │      ICMP Type 3                  │               │
 ▼                                   ▼         (IGMP 스누핑)
[ IP 망 ]                       가입PC(Report)       미가입PC
                                 (나 볼래!)       (방송 안 뿌림)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **ICMP 헤더** | Type과 Code로 **에러 원인을 콕 집어주고**, 원본 패킷 일부를 떼어 보내서 증거를 남김 | IP 안에 캡슐화됨 |
| **IGMP Querier**| 서브넷 라우터 중 대표로 선출돼서 **주기적으로 방송 볼 사람 있냐고 찔러봄** | IP 비교 선출 |
| **IGMP Snooping**| 스위치가 남의 편지 엿듣고 **시청자(가입 포트)한테만 방송을 꽂아줌** | 멍청한 Flooding 차단 |
| **IGMPv1/v2/v3**| v1: 가입만 됨 / v2: "나갈래(Leave)" 기능 추가 / v3: 특정 방송국(SSM)만 골라 보기 | 버전별 기능 차이 |

#### 한줄 요약

- 라우터가 에러 피드백(ICMP) 쏴주고, 스위치는 엿듣기(Snooping)로 볼 사람(IGMP)한테만 방송 틀어준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멀티캐스트(Multicast)**: 똑같은 데이터를 100명한테 줄 때 100번 복사 안 하고, 한 번만 뿌려서 스위치가 알아서 복사하게 만드는 대역폭 절약술이다.

</details>

```text
[ ICMP / IGMP 제어 메시지 십자포화 흐름 ]

[ ICMP 에러 보고 흐름 ]
┌──────────────────────────────┐
│ 1. [라우터] IP 패킷 드롭     │
│ (길 없음 or MTU 너무 큼)     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [ICMP] 송신자에게 에러 쏨 │
│ (Type 3 Code 4 발사!)        │
└──────────────────────────────┘

[ IGMP 방송 가입 흐름 ]
┌──────────────────────────────┐
│ 1. [수신자] IGMP Report 발사 │
│ ("나 239.1.1.1 채널 볼래!")  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [스위치] IGMP 스누핑      │
│ (엿듣고 해당 포트 채널 열어줌)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [라우터] IGMP Querier     │
│ ("ㅇㅋ 거기서 보고 있구만")  │
└──────────────────────────────┘
```

### 동작 원리

- **ICMP 피드백**: 라우터가 전송 실패 원인을 파악해 송신자에게 ICMP Type/Code 에러를 날림.
- **IGMP 동적 포워딩**: 수신자가 Report를 쏘면, 스위치가 엿듣고(Snooping) 해당 포트에만 멀티캐스트 방송을 포워딩함.

#### 한줄 요약

- ICMP는 실패하면 "왜" 실패했는지 쏴주고, IGMP는 "누가" 볼지 손들게 만들어서 쏴준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PMTUD(경로 최대 전송 단위 탐색)**: 패킷 데이터(패킷)를 쪼개지 말고(DF=1) 냅다 쏴봤다가, "크다(Type 3 Code 4)"고 ICMP 맞으면서 최적의 캡슐화된 PDU 데이터 크기를 자동으로 찾아내는 무식하지만 확실한 방법이다.

</details>

| 구분 | **ICMP (에러/진단 통보관)** | **IGMP (멀티캐스트 매니저)** |
|:---|:---|:---|
| 존재 목적 | 1:1 전송 중 길 끊기거나 에러 났을 때 **따지러 가는 용도** | IPTV 켤 때처럼 1:N 방송을 **볼 사람한테만 주려는 용도** |
| 주요 메시지 | 에러(Unreachable), 초과(Time Exceeded), 핑(Echo) | 질문(Query), 가입(Report), 탈퇴(Leave) |
| 대상 트래픽 | **1:1 유니캐스트(Unicast)** 피드백용 | **1:N 멀티캐스트(Multicast)** 통제용 |
| 보안 이슈 | 핑 매우 때려서 CPU 터트림 (Smurf Attack 등) | 아무나 막 쏴서 스위치 뻗게 함 (Unknown Multicast Flooding) |

#### 한줄 요약

- ICMP는 1:1 전송 중 터진 사고를 수습하고, IGMP는 1:N 방송 시청자를 관리한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ICMP 전송률 제한(ICMP Rate Limiting)**: 누가 핑(Ping)으로 장난치면 라우터 CPU가 타버리니까 "1초에 핑 응답 10개만 해!" 하고 강력히 억제하는 세팅이다.
- **알 수 없는 멀티캐스트 플러딩**: 스위치가 엿듣기(Snooping)를 끄고 있으면, 멀티캐스트를 그냥 브로드캐스트 취급해서 온 포트에 다 쏴버려 망이 발생하는 대규모 네트워크 장애다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 방화벽이 보안 핑계로 ICMP 싹 다 막아서 **PMTUD 안 돌고 패킷 깨짐** | 방화벽에서 에러용 **ICMP Type 3 Code 4** 한정 예외적으로 뚫어줌 | MTU 최적화 튜닝(PMTUD) 정상 작동 |
| 해커가 출발지 속이고 대량의 핑을 때려서 **라우터 CPU랑 회선이 터짐** | 라우터에 **ICMP 전송률 제한(Rate Limiting)** 걸어버림 | DDoS 반사 공격(Smurf) 막고 장비 보호 |
| 멀티캐스트 쐈더니 L2 스위치가 온 포트에 다 뿌려서 **트래픽 폭풍 일어남** | L2 스위치에 **IGMP 스누핑** 및 Fast-Leave 무조건 켬 | **알 수 없는 멀티캐스트 플러딩** 완벽 차단 |

#### 한줄 요약

- 핑 공격은 제한 걸고, 에러 ICMP는 뚫어주고, 스위치 엿듣기(Snooping) 켜서 방송 트래픽 새는 걸 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ICMP 선별 허용(Selective ICMP Filtering)**: 핑(Echo)은 막아도 네트워크 튜닝에 필수적인 에러 메시지(Type 3/11 등)는 살려두는 똑똑한 방화벽 정책이다.
- **IGMP 가입 범위 제한**: 멀티캐스트를 아무나 보게 두지 않고 찐으로 허락된 구역(Snooping) 내에서만 뿌리는 최적화 룰이다.

</details>

- 안정적인 패킷 통신 무결성 및 멀티캐스트 인프라 보장을 위해 **ICMP 선별 허용** 정책과 **IGMP 가입 범위 제한** 결합한 L2/L3 트래픽 통제 구현 기조 확립함

#### 한줄 요약

- 막무가내로 다 막지 말고 필수 ICMP만 선별 허용하며, IGMP 스누핑으로 방송 대역폭을 최적화해라.
