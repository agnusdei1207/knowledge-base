## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **VXLAN (가상 확장성 랜, Virtual Extensible LAN)**: 기존 VLAN이 4,000개밖에 못 만들어서 클라우드 시대에 동나버리니까, 이더넷 패킷을 IP/UDP 캡슐화된 PDU 데이터로 한 번 더 포장해서 1,600만 개의 논리적 전용 랜선을 깔아버리는 사기 터널링 기술이다.
- **오버레이 (Overlay) / 언더레이 (Underlay)**: 언더레이는 물리적으로 깔린 진짜 랜선과 라우터(고속도로)들이고, 오버레이는 그 고속도로 위를 날아다니며 자기들끼리만 통신하는 가상의 논리 터널망이다.

</details>

- 정의: **VXLAN** 클라우드 환경에서 기존 VLAN(4,094개)의 한계를 깨부수기 위해, L2 패킷을 L4 UDP로 캡슐화(MAC-in-UDP)해서 물리적 L3 망(언더레이) 위에 1,600만 개의 논리적 L2 가상망(오버레이)을 구축하는 프로토콜이다.
- 배경: 아마존(AWS) 같은 퍼블릭 클라우드에서 수만 명의 고객(테넌트)한테 독립된 가상 네트워크를 쥐여주려다 보니 옛날 VLAN 번호표가 턱없이 부족해져서, **확장성 쩌는 새로운 캡슐화 기술이 필요했다.** #### 한줄 요약

- 기존 VLAN 4천 개 한계를 박살 내고, 1,600만 개의 가상 랜선을 물리적 라우터 망(L3) 위에 깔아버리는 오버레이 마법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VNI (VXLAN Network Identifier)**: 기존 12비트짜리 조막만 한 VLAN ID 대신 24비트로 뻥튀기해서, 최대 1,600만 개의 가상 네트워크를 구별해 내는 넉넉한 고객 번호표다.
- **VTEP (VXLAN Tunnel Endpoint)**: 물리 서버나 스위치 끝단에서 원래 패킷을 VXLAN 상자에 집어넣고(캡슐화), 도착지에서 다시 상자를 뜯어주는(역캡슐화) 포장 센터 겸 터널 출입구다.

</details>

- **24비트 VNI 뻥튀기 확장성**: 식별자 공간이 약 1,600만 개로 팍 늘어나서, 전 세계 클라우드 고객들한테 각자 전용 망을 쥐여줘도 번호표가 남는다.
- **MAC-in-UDP 패킷 데이터 포장 (캡슐화)**: 물리 서버에서 나온 원본 이더넷 패킷(MAC)에다가 VXLAN 라벨을 붙이고 UDP 상자로 한 번 더 포장해서, 밑바닥 물리 라우터들을 속이고 마음대로 수송한다.
- **MP-BGP EVPN (제어 평면 억제)**: 옛날엔 수신자를 모르면 일단 동네방네 복제해서 다 뿌렸는데(BUM 트래픽), 이제는 BGP로 "어느 MAC이 어느 VTEP에 있다"고 주소록을 쫙 돌려서 쓰잘데기없는 브로드캐스트 플러딩을 틀어막는다.

#### 한줄 요약

- 1,600만 개(VNI)의 넉넉한 가상망, MAC-in-UDP 캡슐화 포장, 주소록 미리 돌리는 EVPN 연동이 3대 핵심 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BUM 트래픽 (플러딩)**: 브로드캐스트(B), 알 수 없는 유니캐스트(U), 멀티캐스트(M)의 약자로, 스위치가 목적지를 몰라서 무식하게 모든 랜포트로 쫙 뿌려버리는 민폐 쓰레기 트래픽이다.
- **ECMP (등가 다중 경로)**: 물리 고속도로(L3 언더레이)를 달릴 때 안 막히는 차선 여러 개를 동시에 다 써서 대역폭을 과도하게 뽑아내는 로드밸런싱 기술이다.

</details>

```text
[ VXLAN 오버레이 직관적 비교 구조 ]

[ 오버레이 계층 (논리적 가상 네트워크) ]
      │ (VNI 100번 고객망, VNI 200번 고객망)
      ▼
[ VTEP (캡슐화 포장 센터) ] ── (원본 패킷을 UDP 박스에 포장함)
      │
      ▼ (MAC-in-UDP 캡슐화 트래픽 수송)
[ 언더레이 계층 (물리적 L3 패브릭) ] ── (스파인-리프 물리 라우터들의 ECMP 고속도로)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **VTEP (터널 종단점)** | 원본 패킷을 UDP 상자에 캡슐화하고 도착지에서 다시 뜯어주는 **터널 패킷 데이터 포장소** | Edge |
| **VNI (가상망 식별자)** | 1,600만 명까지 수용 가능한 **24비트짜리 넉넉한 고객 구분 번호표** | VXLAN Header |
| **오버레이 (Overlay)** | 밑바닥 물리 장비들 눈치 안 보고 VTEP끼리 하늘로 뚫어놓은 **가상의 전용 L2 통로** | Virtual |
| **언더레이 (Underlay)** | VTEP끼리 연결해 주고 UDP 상자를 빡세게 날라주는 **진짜 쇳덩어리 물리 L3 인프라** | Physical |
| **MP-BGP EVPN (제어)** | "누가 어디 있냐" 소리 지르기 전에 주소록(MAC/IP)을 쫙 돌려서 **플러딩 막아주는 두뇌** | Control Plane |

#### 한줄 요약

- VTEP이 패킷 데이터 포장(캡슐화)을 하면, 밑바닥 언더레이 라우터들이 그 짐을 날라서, 반대편 VTEP이 오버레이 가상망에 풀어놓는 2층 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ VXLAN 캡슐화 포장 수송 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [원본 L2 프레임 발송]     │
│ (가상머신 A: 가상머신 B한테 데이터 쏜다)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [송신 VTEP 매핑 조회 (EVPN)]│
│ (포장소: 오케이. B가 어느 물리 장비 쪽에 있나?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [VXLAN + UDP 캡슐화 (포장)]│
│ (포장소: VNI 번호표 붙이고 UDP 박스에 쑤셔 넣음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [L3 언더레이 ECMP 고속 수송]
│ (물리 라우터망: 알맹이는 모르겠고 도착지로 쏜다)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [수신 VTEP 역캡슐화 (박스 개봉)]
│ (도착지 VTEP: 박스 뜯고 알맹이 꺼내서 VM B한테 줌)
└──────────────────────────────┘
```

### 동작 원리

1. 원본 패킷 발송: 가상머신(VM)에서 순수한 오리지널 이더넷 프레임을 만들어 보냄.
2. VTEP 주소 조회: VTEP가 목적지 VM이 연결된 반대편 VTEP의 물리 IP 주소를 주소록(EVPN)에서 찾음.
3. Outer 헤더 캡슐화: 원본 프레임 앞에 VXLAN VNI, UDP, IP 헤더를 덧붙여서 캡슐을 씌움.
4. 물리망(언더레이) 전송: 스파인-리프 물리 스위치들이 IP 주소만 보고 패킷을 전달함.
5. 역캡슐화: 목적지 VTEP가 도착한 UDP 상자를 뜯고 외부 캡슐화 래퍼를 버린 뒤, 순수 프레임만 목적지 VM에 꽂아줌.

#### 한줄 요약

- 원본 패킷 발송 $\to$ VTEP이 목적지 찾음 $\to$ 캡슐화 포장 $\to$ 물리 라우터 수송 $\to$ 도착 후 박스 개봉(역캡슐화)의 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **VLAN (Virtual LAN)**: 스위치에 태그(12비트)를 낑겨 넣어서 네트워크를 쪼개는 기술인데, 4,094개 한계가 있고 스위치들끼리 랜선(L2)으로 다 이어져 있어야 하는 옛날 꼰대 기술이다.

</details>

| 구분 | **VXLAN (오버레이 가상망)** | **VLAN (물리 스위치 가상망)** |
|:---|:---|:---|
| 핵심 특징 | 라우터망 위를 날아다니는 **클라우드형 1,600만 수저** | 랜선 꼽힌 스위치만 기어 다니는 **동네 4천 수저** |
| 캡슐화/태그 방식 | IP 안에 MAC을 구겨 넣는 **MAC-in-UDP 캡슐화** | 이더넷 프레임 중간에 **802.1Q 12비트 태그 낑겨넣음** |
| 가상망 식별 개수 | 24비트 VNI 써서 **최대 1,600만 개 씹가능** | 12비트 VID 써서 **4,094개 한계 (클라우드에서 금방 동남)** |
| 기반 인프라 종속 | 스위치가 달라도 IP망(L3)만 뚫려 있으면 **어디든 다 됨** | 물리 스위치끼리 전부 다 L2 랜선으로 **이어져 있어야 함** |
| 경로 대역폭 효율 | L3 ECMP 써서 물리망 여러 길로 **트래픽 과도하게 분산함** | 루프 막으려고 STP 써서 **길 하나를 아예 막아버림 (낭비)** |

#### 한줄 요약

- VLAN은 4천 개짜리 스위치 랜선 전담자고, VXLAN은 라우터 IP망을 날아다니면서 1,600만 개 세그먼트를 뚫어버리는 캡슐화 깡패다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **점보 프레임 (MTU 확장)**: VXLAN 캡슐화한다고 헤더(50바이트)를 덧붙이면 패킷 데이터 박스가 뚱뚱해져서 라우터가 자르려 드니까, 아예 통과 문(MTU) 크기를 1550이나 9000으로 큼지막하게 뚫어놓는 거다.
- **SmartNIC / DPU (오프로드)**: 포장(캡슐화) 수작업 반복를 서버 CPU가 직접 뛰면 서버가 뻗으니까, 랜카드 칩셋이 대신 캡슐화 수작업 반복를 뛰게 해서 CPU를 쉬게 해주는 하드웨어 가속기다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 패킷 데이터 뚱뚱하다고 라우터가 **패킷을 반갈죽(단편화) 시켜버림** | 패킷에 VXLAN 헤더 50바이트를 덧붙여서 기존 MTU(1500) 규격을 초과해 버림 | 언더레이 물리 장비의 **MTU 사이즈를 1550~9000 점보 프레임으로 늘림** | 패킷 쪼개졌다 합쳐지는 오버헤드 컷트 및 속도 저하 차단 |
| 도착지 모른다고 **동네방네 BUM 플러딩 민폐 과도하게 줌** | 목적지 MAC을 모르면 VTEP가 싹 다 복제해서 뿌려버림 (대역폭 낭비) | **MP-BGP EVPN 연동 및 ARP Suppression(억제)** 세팅으로 컨트롤 면에서 컷트 | 데이터 평면 쓰레기 트래픽 청소 및 대역폭 낭비 방지 |
| 서버가 패킷 포장하느라 **CPU 부하 걸려서 뻗음** | 수만 개의 패킷을 서버 CPU가 직접 UDP 상자에 포장(캡슐화)하느라 뻗음 | 캡슐화 포장 수작업 반복는 **SmartNIC/DPU (VXLAN Offload 칩)에 다 짬처리시킴** | 서버 CPU 부하율 급격한 저하 및 초고속 라인 레이트 캡슐화 |

#### 한줄 요약

- 캡슐 씌웠다고 패킷 잘리지 않게 MTU 팍 늘려주고(점보 프레임), 민폐 BUM 트래픽은 EVPN으로 막고, 포장 수작업 반복는 랜카드(SmartNIC)에 떠넘겨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 4,094개의 빈약한 수용량과 물리 랜선 족쇄에 종속되는 VLAN의 한계를 박살 내기 위해, **MAC-in-UDP 캡슐화** 및 **24비트 VNI** 활용 앞세운 VXLAN 오버레이 네트워크 아키텍처 기조 확립함

#### 한줄 요약

- VXLAN은 단순한 태그놀이를 넘어서 물리적 망 구조에 얽매이지 않고 클라우드를 무한대로 찢어발기는 오버레이 마법이다.
