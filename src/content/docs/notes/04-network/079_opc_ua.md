## 미리 알고가기

- **개방형 플랫폼 통신 통합 아키텍처(Open Platform Communications Unified Architecture, OPC UA)**: 산업 데이터의 의미·서비스·보안을 통합한 상호운용 표준
- **프로그램 가능 논리 제어기(Programmable Logic Controller, PLC)**: 센서 입력과 제어 논리로 기계·설비를 동작시키는 산업용 제어기
- **감시 제어 및 데이터 수집(Supervisory Control and Data Acquisition, SCADA)**: 설비 상태를 중앙 수집·표시하고 원격 제어하는 시스템
- **제조 실행 시스템(Manufacturing Execution System, MES)**: 생산 지시·공정 실적·품질·설비 상태를 관리하는 제조 운영 시스템
- **정보 모델(Information Model)**: 설비의 값·자료형·단위·속성·관계를 함께 표현하는 의미 구조
- **주소 공간(Address Space)**: 서버가 객체·변수·메서드 노드와 참조를 공개하는 정보 구조
- **노드(Node)**: 주소 공간에서 설비·값·형식·동작을 표현하는 정보 요소
- **참조(Reference)**: 원천 노드와 대상 노드 사이의 관계 유형을 표현하는 연결 정보
- **보안 채널(Secure Channel)**: 애플리케이션 인증서로 메시지 무결성·기밀성을 보호하는 통신 채널
- **세션(Session)**: 사용자의 인증·권한과 서비스 요청을 연결하는 논리적 상호작용 단위
- **발행·구독(Publish-Subscribe, PubSub)**: 발행자가 데이터 집합을 배포하고 관심 구독자가 수신하는 통신 모델
- **컴패니언 명세(Companion Specification)**: 산업별 장비·데이터 의미를 공통 OPC UA 정보 모델로 정의한 명세
- **OPC 10000 시리즈**: OPC UA의 개념·보안·주소 공간·서비스·PubSub를 규정한 표준군
- **애플리케이션 인증서(Application Certificate)**: OPC UA 프로그램의 신원과 공개키를 연결하는 인증서
- **접속점(Endpoint)**: 서버 주소·보안 정책·메시지 보안 모드를 함께 공개한 연결 지점
- **신뢰 목록(Trust List)**: 통신을 허용할 인증기관과 애플리케이션 인증서를 모은 목록
- **데이터 집합(Data Set)**: PubSub 발행자가 함께 배포하는 변수와 메타데이터 묶음
- **전송 매핑(Transport Mapping)**: OPC UA 메시지를 구체적인 전송 프로토콜에 대응시키는 규칙

## Ⅰ. 개요

- 정의/개념: 산업 데이터의 의미·서비스·보안을 통합한 **상호운용 표준**
- 배경/필요성: 제조사별 원시 값은 **이름·단위·품질 의미 공유 불가**

### 쉽게 이해하기 (학습용)

- OPC UA는 값뿐 아니라 설비 이름·자료형·단위·품질을 함께 전달해 서로 다른 시스템이 같은 뜻으로 해석하게 한다.

## Ⅱ. 특징

- **의미 모델**: 노드·속성·참조로 산업 데이터 표현
- **표준 서비스**: 탐색·읽기·쓰기·호출 인터페이스
- **계층 보안**: 인증서로 프로그램, 역할로 사용자 통제

### 쉽게 이해하기 (학습용)

- 같은 숫자도 단위와 품질 의미가 다르면 오해하므로 송수신 시스템이 공통 정보 모델을 사용해야 한다.

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
    columns 1
    CLIENT["클라이언트·PubSub 소비자"]
    SERVER["OPC UA 서버"]
    MODEL["정보 모델·주소 공간"]
    DEVICE["PLC·센서"]
    SECURITY["인증서·역할 정책"]
    DEVICE --> MODEL
    MODEL --> SERVER
    SERVER --> CLIENT
    SECURITY --> SERVER
    SECURITY --> CLIENT
```

| 구성요소 | 책임 |
|:---|:---|
| PLC·센서 | 설비 값 생성과 제어 명령 실행 |
| 정보 모델·주소 공간 | 노드·속성·참조에 의미 부여 |
| OPC UA 서버 | 주소 공간과 표준 서비스 제공 |
| 클라이언트·PubSub 소비자 | 탐색·제어 요청과 데이터 활용 |
| 인증서·역할 정책 | 애플리케이션 신뢰와 권한 제한 |

### 쉽게 이해하기 (학습용)

- 서버의 주소 공간이 원시 설비값에 이름·자료형·단위·관계를 붙여 상위 시스템이 같은 의미로 사용하게 한다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant C as OPC UA 클라이언트
    participant S as OPC UA 서버
    C->>S: 1. 접속점 탐색
    S-->>C: 보안 정책·서버 인증서
    C->>S: 2. 보안 채널 생성
    S-->>C: 채널 승인
    C->>S: 3. 세션 활성화
    S-->>C: 사용자 역할 적용
    C->>S: 4. 주소 공간 탐색
    S-->>C: 노드·속성·참조
    C->>S: 5. 데이터 서비스 사용
    S-->>C: 값·품질·측정 시각
```

1. **접속점 탐색**: 주소·지원 정책·서버 인증서 확인
2. **보안 채널 생성**: 애플리케이션 신뢰와 메시지 보호 설정
3. **세션 활성화**: 사용자 인증 후 역할 권한 연결
4. **주소 공간 탐색**: 노드·속성·참조로 설비 의미 발견
5. **데이터 서비스 사용**: 읽기·쓰기·호출·구독 수행

### 쉽게 이해하기 (학습용)

- 인증서는 프로그램 신원을 확인하고 사용자 역할은 세션에서 접근 가능한 노드와 작업을 제한한다.

## Ⅴ. 종류 및 비교

| OPC UA 통신 모델 | 클라이언트·서버 | 발행·구독 |
|:---|:---|:---|
| 적용 기준 | **탐색·진단·개별 제어** | **다대다 주기 배포** |
| 핵심 특징 | 주소 공간의 **서비스 요청·응답** | 데이터 집합의 **비결합 배포** |
| 한계 | 세션·구독 증가의 **서버 부하** | 전달 보장의 **전송 매핑 의존** |

### 쉽게 이해하기 (학습용)

- 설비를 탐색해 개별 제어하면 클라이언트·서버, 같은 데이터를 여러 시스템에 배포하면 PubSub가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 제조사별 **의미 모델 불일치** | 컴패니언 명세와 **매핑 규칙** 적용 | MES 연계의 **의미 일관성** |
| 인증서 만료의 **통신 중단** | 신뢰 목록·갱신 **자동화** | 보안 채널의 **운영 연속성** |
| 대규모 구독의 **서버 과부하** | 샘플링·큐·PubSub **분산 설계** | 지연과 **서버 부하 감소** |

### 쉽게 이해하기 (학습용)

- 제조사마다 다른 PLC 값을 공통 정보 모델로 매핑하면 MES가 이름·단위·품질을 같은 의미로 해석할 수 있다.

## Ⅶ. 결론

- 공통 의미는 **컴패니언 명세**, 개별 제어는 **클라이언트·서버**, 다대다는 **PubSub**

### 쉽게 이해하기 (학습용)

- 공통 의미 모델을 먼저 맞추고 개별 제어는 클라이언트·서버, 대량 배포는 PubSub로 설계한다.
