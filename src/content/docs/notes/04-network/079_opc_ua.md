## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **개방형 플랫폼 통신 통합 아키텍처(Open Platform Communications Unified Architecture, OPC UA)**: 산업 데이터의 값•자료형•단위•관계와 서비스•보안을 함께 규정하는 상호운용 표준이다.

</details>

- 정의/개념: **OPC UA**는 산업 데이터의 의미•서비스•보안을 통합한 상호운용 표준이다.
- 배경/필요성: 제조사별 원시 값만으로는 이름•단위•품질 의미를 공유할 수 없다.

#### 한줄 요약

- OPC UA는 값뿐 아니라 설비 이름•자료형•단위•품질을 함께 전달해 서로 다른 시스템이 같은 뜻으로 해석하게 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **계층 보안(Layered Security)**: 애플리케이션 인증서와 세션 사용자 역할로 프로그램 신원과 노드별 작업 권한을 나눠 통제하는 방식이다.

</details>

- **계층 보안**: 인증서로 프로그램, 역할로 사용자를 통제한다.

#### 한줄 요약

- 같은 숫자도 단위와 품질 의미가 다르면 오해하므로 송수신 시스템이 공통 정보 모델을 사용해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정보 모델(Information Model)**: 설비 데이터의 이름•자료형•단위•관계를 정의하는 모델이다.
- **주소 공간(Address Space)**: 정보 모델의 노드•속성•참조를 제공하는 논리 공간이다.
- **프로그래머블 논리 제어기(Programmable Logic Controller, PLC)**: 현장의 센서 값을 수집하고 제어 논리를 실행하는 산업 제어 장치이다.
- **OPC UA 발행•구독(OPC UA Publish-Subscribe, OPC UA PubSub)**: 데이터 집합을 생산자와 소비자 사이에 비결합 배포하는 모델이다.

</details>

- **정보 모델**을 **주소 공간**의 노드•속성•참조로 제공하고 **PLC** 데이터를 **OPC UA PubSub**로 비결합 배포할 수 있다.

```text
OPC UA
├─ PLC•센서
├─ 정보 모델•주소 공간
├─ OPC UA 서버
├─ 클라이언트•PubSub 소비자
└─ 인증서•역할 정책
```

선의 의미: 가로선은 현장 설비, 의미를 부여하는 정보 모델•주소 공간, 이를 제공하는 OPC UA 서버와 데이터를 활용하는 소비자의 정적 결합 관계이고, 위 가지는 인증서•역할 정책이 서버와 소비자의 신뢰•권한 경계를 함께 제한하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| PLC•센서 | 설비 값•제어 명령 실행 |
| 정보 모델•주소 공간 | 노드•속성•참조 의미 부여 |
| OPC UA 서버 | 주소 공간•표준 서비스 제공 |
| 클라이언트•PubSub 소비자 | 탐색•제어•데이터 활용 |
| 인증서•역할 정책 | 애플리케이션 신뢰•권한 제한 |

#### 한줄 요약

- 서버의 주소 공간이 원시 설비값에 이름•자료형•단위•관계를 붙여 상위 시스템이 같은 의미로 사용하게 한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보안 채널 생성(Secure Channel Establishment)**: 신뢰된 애플리케이션 인증서와 정책을 검증해 메시지 무결성•기밀성을 보호하는 채널 수립 과정이다.
- **접속점 탐색**: 서버 주소•지원 보안 정책•애플리케이션 인증서를 확인하는 단계이다.
- **세션 활성화**: 보안 채널 위에서 사용자를 인증하고 역할 권한을 연결하는 단계이다.
- **주소 공간 탐색**: 노드•속성•참조를 조회해 설비 데이터의 의미와 관계를 찾는 단계이다.
- **데이터 서비스 사용**: 권한 범위 안에서 읽기•쓰기•호출•구독을 수행하는 단계이다.

</details>

```text
1. 접속점 탐색
      │
      ▼
보안 정책•서버 인증서 확인
      │
      ▼
2. 보안 채널 생성
      ├─ 인증서 불신: 연결 차단
      └─ 신뢰: 채널 승인
          │
          ▼
3. 세션 활성화
          │
          ▼
사용자 역할 적용
          │
          ▼
4. 주소 공간 탐색
          │
          ▼
5. 데이터 서비스 사용
          │
          ▼
값•품질•측정 시각 반환
```

### 동작 원리

1. 접속점 탐색: **접속점 탐색** 단계에서 주소•지원 정책•서버 인증서를 확인한다.
2. 보안 채널 생성: **보안 채널 생성** 단계에서 애플리케이션 신뢰와 메시지 보호를 설정한다.
3. 세션 활성화: **세션 활성화** 단계에서 사용자 인증 후 역할 권한을 연결한다.
4. 주소 공간 탐색: **주소 공간 탐색** 단계에서 노드•속성•참조로 설비 의미를 발견한다.
5. 데이터 서비스 사용: **데이터 서비스 사용** 단계에서 읽기•쓰기•호출•구독을 수행한다.

#### 한줄 요약

- 인증서는 프로그램 신원을 확인하고 사용자 역할은 세션에서 접근 가능한 노드와 작업을 제한한다.

## Ⅴ. 종류 및 비교

| OPC UA 통신 모델 | 클라이언트•서버 | 발행•구독 |
|:---|:---|:---|
| 적용 기준 | 탐색•진단•개별 제어 | **OPC UA PubSub**는 다대다 주기 배포 |
| 핵심 특징 | 주소 공간의 서비스 요청•응답 | 데이터 집합의 비결합 배포 |
| 한계 | 세션•구독 증가의 서버 부하 | 전달 보장의 전송 매핑 의존 |

#### 한줄 요약

- 설비를 탐색해 개별 제어하면 클라이언트•서버, 같은 데이터를 여러 시스템에 배포하면 PubSub가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인증서 기반 통신 중단(Certificate-Induced Communication Failure)**: 인증서 만료나 신뢰 목록 갱신 실패로 보안 채널을 수립하지 못하는 문제이다.
- **제조 실행 시스템(Manufacturing Execution System, MES)**: 생산 계획과 현장 설비 실적•품질 정보를 연계해 제조 활동을 관리하는 시스템이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제조사별 정보 모델 불일치 | 컴패니언 명세와 매핑 규칙 적용 | **MES** 연계의 의미 일관성 |
| 인증서 기반 통신 중단 | 신뢰 목록•갱신 자동화 | 보안 채널의 운영 연속성 |
| 대규모 구독의 서버 과부하 | 샘플링•큐•PubSub 분산 설계 | 지연과 서버 부하 감소 |

#### 한줄 요약

- 제조사마다 다른 PLC 값을 공통 정보 모델로 매핑하면 MES가 이름•단위•품질을 같은 의미로 해석할 수 있다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **컴패니언 명세(Companion Specification)**: 산업별 장비•데이터의 이름•단위•속성•관계를 공통 OPC UA 정보 모델로 정한 명세이다.

</details>

- 공통 의미는 **컴패니언 명세**, 개별 제어는 클라이언트•서버, 다대다는 **OPC UA PubSub**가 핵심이다.

#### 한줄 요약

- 공통 의미 모델을 먼저 맞추고 개별 제어는 클라이언트•서버, 대량 배포는 PubSub로 설계한다.
