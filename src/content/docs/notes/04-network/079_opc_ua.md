## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **OPC UA (개방형 플랫폼 통신 통합 아키텍처)**: 지멘스, 미쓰비시 등 제조사마다 제각각이던 기계어(데이터)를 통일해서, 단순히 숫자만 던지는 게 아니라 "이건 온도고, 단위는 섭씨고, 현재 정상이다"라는 의미(Context)까지 싹 다 담아서 공유하는 스마트 팩토리 궁극의 표준 통신망이다.

</details>

- 정의: **OPC UA**는 산업 현장의 단순한 센서값(Raw Data)에 의미, 서비스, 강력한 보안을 짬뽕해서 서로 다른 설비들이 찰떡같이 말귀를 알아먹게 해주는 **상호운용 표준 프로토콜**이다.
- 배경: 옛날엔 기계가 '35'라는 숫자만 던져서 이게 온도인지 펌프 압력인지 사람이 일일이 수동 세팅해야 했지만, **기계끼리 팩트 체크 없이도 USB 꽂듯 바로 소통(Plug & Play)하려고 뼈대부터 다시 설계했다.**

#### 한줄 요약

- 데이터 값만 덜렁 보내는 게 아니라 "나는 1번 펌프고, 이 값은 섭씨 온도다"라고 설명서까지 같이 보내서 공장 기계들끼리 대화하게 만드는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **계층 보안 (Layered Security)**: 공장 기계가 해킹당하면 사람 목숨이 날아가니까, 기계끼리 연결될 때(인증서) 한 번 거르고, 사람(사용자)이 접속할 때 역할 권한(Role)으로 또 한 번 거르는 철벽 방어 시스템이다.

</details>

- **설명충 데이터 (정보 모델)**: "나 펌프 1호기인데, 온도는 30도고, 정상 작동 중이고, 내 부품 번호는 이거야" 하고 자기소개서를 데이터에 딱 붙여서 보낸다.
- **OS/플랫폼 독립적**: 예전(OPC Classic)엔 윈도우(COM/DCOM)에서만 돌아가는 반쪽짜리였는데, 이젠 리눅스, 안드로이드, 클라우드 가릴 것 없이 다 돌아간다.
- **철벽 계층 보안**: 통신 암호화는 기본이고, 애플리케이션(기계) 인증서로 신분증 검사부터 빡세게 하고, 사용자 역할(Role)로 스위치 누를 수 있는 권한을 따로 쪼개서 통제한다.

#### 한줄 요약

- OS 안 가리고, 데이터에 설명서 달아주고, 해킹당하면 큰일 나니까 이중 삼중으로 보안을 쳐놓은 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정보 모델 (Information Model)**: 설비의 데이터 이름, 속성, 단위를 어떻게 부를지 룰을 정해둔 팩트 체크 사전이다.
- **주소 공간 (Address Space)**: 그 사전(정보 모델)을 바탕으로, "1번 펌프는 A방에 있고, 온도는 B서랍에 있다"고 폴더 트리(Tree) 구조로 정리해 놓은 데이터베이스다.

</details>

```text
[ OPC UA 스마트 팩토리 팩트 폭행 구조 ]

[ 1. PLC 및 센서 ] ── (현장에서 35도라는 데이터 생산함)
      │
      ▼
[ 2. OPC UA 서버 ] ── (이 데이터는 섭씨 35도고 펌프1 온도다! 하고 정보 모델 덮어씌움)
      │
      ├─► [ 3. 정보 모델 / 주소 공간 ] ── (폴더 트리 형태로 데이터 예쁘게 분류해 놓음)
      │
      ▼
[ 4. 클라이언트 / PubSub 소비자 ] ── (서버에 붙어서 "펌프1 온도 내놔" 하고 편하게 가져감)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **PLC / 센서** | 현장에서 **기계 돌리면서 원시 데이터(Raw) 뽑아내는 노가다 장비** | Field Device |
| **OPC UA 서버** | 원시 데이터에 **"이건 펌프 온도다" 하고 의미(Context) 씌워주는 통역사** | Server |
| **정보 모델/주소 공간** | 폴더 구조(Tree)로 **기계 데이터들을 찾기 쉽게 정리해 놓은 파일 탐색기** | Address Space |
| **클라이언트 (MES 등)** | 서버에 접속해서 **데이터 편하게 빼먹고 공장 셧다운 명령 때리는 본사 시스템** | Client |

#### 한줄 요약

- 밑에서 기계(PLC)가 값 올리면 $\to$ 서버가 정보 모델로 예쁘게 포장해서 $\to$ 위쪽 클라이언트가 쏙쏙 빼먹는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보안 채널 생성**: 통신 시작할 때 "너 진짜 허가받은 기계(App) 맞냐?" 하고 인증서로 기계끼리 신뢰의 암호화 터널을 뚫는 거다.
- **세션 활성화**: 터널 뚫은 다음, "접속한 너 공장장이야 알바생이야?" 하고 사람의 권한(Role)을 체크해서 건드릴 수 있는 범위를 정하는 거다.

</details>

```text
[ OPC UA 보안 및 데이터 교환 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [접속점 탐색 및 헬스 체크]│
│ (클라이언트: 너 OPC UA 서버 맞지? 보안 스펙 뭐 쓰냐?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [보안 채널 생성 (App 인증)]
│ (서버: 내 신분증(인증서) 깔게. 너도 까라. 암호화 터널 뚫자!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [세션 활성화 (User 권한)] │
│ (서버: 터널은 뚫렸고, 너 알바생이네? 읽기 권한만 준다)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [주소 공간 탐색 (Browse)] │
│ (클라이언트: 폴더 트리 열어봐. 1번 펌프 온도 어딨어?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [데이터 Read/Write 집행]  │
│ (결과: 펌프 온도값 수신 완료, 모터 정지 명령 하달)
└──────────────────────────────┘
```

### 동작 원리

1. 접속점 탐색: 클라이언트가 서버 IP를 치고 들어가서 "어떤 보안 수준 지원해?" 하고 입구를 찾음.
2. 보안 채널 생성: 기계 대 기계(App to App)로 서로의 X.509 **인증서**를 까서 신뢰할 수 있는지 팩트 체크함.
3. 세션 활성화: 인증된 터널 위에서 ID/PW 등으로 사용자 로그인을 받아 **권한(역할)** 을 줌.
4. 주소 공간 탐색: 내 컴퓨터 폴더 뒤지듯이, 주소 공간(트리 구조)을 돌아다니며 내가 원하는 설비 노드(Node)를 찾음.
5. 서비스 사용: 읽기, 쓰기, 아니면 "바뀔 때만 알려줘(구독)" 등의 짓거리를 권한 한도 내에서 수행함.

#### 한줄 요약

- 기계 인증(인증서) $\to$ 사람 인증(로그인) $\to$ 데이터 위치 찾기 $\to$ 명령 때리기의 철저한 4단계 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Pub/Sub (발행/구독) 모델**: 기계 수만 대가 클라이언트 하나에 다 붙으면 서버가 터지니까, 그냥 허공에 "데이터 쏠 테니 필요한 놈들 가져가라!" 하고 라디오처럼 방송(Broadcast)해 버리는 거다.

</details>

| 통신 모델 비교 | **클라이언트-서버 (Client/Server)** | **OPC UA Pub/Sub (발행/구독)** |
|:---|:---|:---|
| 팩트 폭행 비유 | "야, 이거 해라!" **1:1로 직접 쪼는 방식** | "나 데이터 쏜다~" **라디오 방송 방식** |
| 적용 기준 | 내가 **원할 때마다 정밀하게 찔러서 값을 읽거나 제어할 때** | 1초마다 **똑같은 값을 수십 대의 서버에 쫙 뿌려야 할 때** |
| 핵심 특징 | 주소 공간 트리를 뒤져서 **TCP 기반으로 요청/응답함** | 브로커(MQTT)나 멀티캐스트 써서 **가볍게 데이터 툭 던짐** |
| 치명적 한계 | 수만 대 기계 붙으면 **서버 CPU 터지고 세션 감당 안 됨** | 던지고 마는 거라 **전달 보장 빡세게 하려면 별도 세팅 필요** |

#### 한줄 요약

- 정밀하게 하나씩 패고 싶으면 클라이언트-서버, 여러 놈한테 한 방에 뿌리고 싶으면 Pub/Sub 모델을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **컴패니언 명세 (Companion Specification)**: "로봇 팔은 데이터 이름 이렇게 통일하자!" 하고 지멘스, 미쓰비시 같은 웬수 같은 경쟁사들이 모여서 억지로 만든 산업별 공통 표준 단어장이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 지멘스랑 미쓰비시 기계가 **서로 데이터 뜻을 못 알아먹음** | 같은 펌프라도 지멘스는 'Temp', 미쓰비시는 '온도'로 정보 모델(이름)을 맘대로 짬 | 공장 표준 단어장인 **컴패니언 명세(Companion Spec)로 강제 맵핑 시켜버림** | MES 시스템 연동 시 뻘짓 줄이고 100% 의미 일관성 확보 |
| 갑자기 공장 전체 기계가 **통신 중단되고 셧다운 됨** | 기계에 박아둔 보안 인증서 유효기간(1년)이 만료돼서 보안 채널이 강제 차단됨 | 사람이 일일이 USB로 굽지 말고 **GDS(인증서 중앙 관리 서버)로 자동 갱신 켬** | 인증서 만료로 공장 멈추는 어이없는 대참사 방지 |
| C/S 모델 썼더니 **데이터 읽느라 서버 CPU 100% 쳐버림** | 클라이언트 수백 개가 1초마다 뻔한 데이터 달라고 서버 찔러대서 오버헤드 터짐 | 찌르지 말고, 변경될 때만 던져주는 **구독(Subscription)이나 아예 Pub/Sub 모델로 갈아엎음** | 무의미한 통신 부하 싹 줄이고 네트워크 대역폭 확보 |

#### 한줄 요약

- 벤더사 마음대로 짠 단어 싹 다 컴패니언 명세로 통일시키고, 인증서 만료 체크 안 하면 공장 멈춘다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 제조사 벤더 종속성을 탈피하고 데이터를 의미 있게 교환하기 위해, **정보 모델 기반 주소 공간**, **계층 보안**, **C/S 및 Pub/Sub 이중 통신**을 결합한 스마트 팩토리 OPC UA 기조 확립함

#### 한줄 요약

- OPC UA는 말 안 통하는 전 세계 공장 기계들을 하나로 묶어주는 스마트 팩토리 시대의 만국 공통어다.
