## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **이더넷 프레임(Ethernet Frame)**: 랜선(L1)을 타고 온 0과 1의 쓰레기 데이터들을 의미 있는 한 덩어리로 묶어서 봉투(L2)에 담아낸 기본 택배 상자다.
- **MAC 주소(Media Access Control Address)**: 랜카드 기판에 공장 출고 때부터 팍 박혀 나오는 48비트짜리 절대 안 변하는 하드웨어 고유 번호판(주민번호)이다.

</details>

- 정의: MAC 주소(출발/도착지)와 페이로드, 에러 검출기(FCS)를 묶어 캡슐화한 **L2 전송 데이터 단위**
- 배경: 0과 1이 날아다니는 비트스트림만으로는 **어디서 시작하고 누가 받을지, 오다가 깨졌는지 알 방법이 없었기 때문**

#### 한줄 요약

- 랜선에서 0과 1의 쓰레기 데이터를 주워 모아 누가 보냈고 누구한테 갈지 명시한 L2 택배 상자다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **프리앰블(Preamble) 및 SFD**: 택배차 들어올 때 "삐-삐-삐-이제 진짜 들어간다!" 하고 박자를 맞춰서 수신 준비를 시키는 오프닝 알람 비트다.
- **프레임 검사 시퀀스(FCS)**: 택배(프레임) 꼬리에 달린 바코드 보안 씰로, 랜선 타고 오다 구겨지거나 에러(비트 변조) 나면 가차 없이 쓰레기통에 버리는 검증 꼬리표다.

</details>

- **프리앰블** 및 **SFD(프레임 시작 구분자)** 필드를 통해 물리적 박자를 맞추고 "지금부터 진짜 데이터다!" 하고 시작점을 명확화.
- 목적지와 출발지의 6바이트 MAC 주소를 까보고 L2 스위치가 어느 포트로 쏠지 기계적으로 스위칭.
- 꼬리에 달린 **프레임 검사 시퀀스(FCS)** 로 계산기를 두드려보고 1비트라도 깨졌으면 즉시 버려버림(고치는 건 L4 몫).

#### 한줄 요약

- 박자(Preamble) 맞추고, 주소(MAC) 보고 던지며, 꼬리표(FCS)로 에러 나면 얄짤없이 찢어버린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이더타입(EtherType)**: 봉투 겉면에 "이 안에 든 건 IPv4 패킷이야(0x0800)" 하고 까보지 않아도 내용물 종류를 알려주는 2바이트 네임택이다.
- **CRC-32(Cyclic Redundancy Check-32)**: 에러 났는지 수학적으로 다항식을 미친 듯이 연산해서 FCS 필드에 채워 넣는 32비트짜리 에러 검출 공식이다.

</details>

```text
[ 이더넷 프레임 팩트 폭행 레이아웃 ]

[ 머리 (Header) ]                     [ 몸통 (Payload) ]        [ 꼬리 (Trailer) ]
+------------------------------------+--------------------------+----------------+
| Preamble | 목적지 MAC | 출발지 MAC | 이더타입 |  IP 데이터 페이로드  |      FCS       |
| (박자맞춤) |  (너한테)  |  (내가 쏨) | (IPv4임) |  (최대 1500바이트)  | (에러검출기)   |
+----------+----------+------------+----------+--------------------------+----------------+
| 8 Bytes  | 6 Bytes  | 6 Bytes    | 2 Bytes  |    46 ~ 1500 Bytes     | 4 Bytes        |
+------------------------------------+--------------------------+----------------+
```

| 구성요소 | 바이트 크기 | 팩트 폭행 책임 |
|:---|:---|:---|
| **Preamble + SFD** | 8 Bytes | "자 지금부터 패킷 쏠 테니까 박자(클록) 맞춰!" 하고 던지는 신호탄 |
| **Dest / Src MAC** | 각 6 Bytes | "이 주민번호 가진 놈 받아라 / 내가 보냈다" (스위치 학습 기준) |
| **EtherType** | 2 Bytes | "이 상자 안에 든 건 IPv4(0x0800)야 ARP(0x0806)야" 하고 명시함 |
| **Data Payload** | 46 ~ 1500 B | 진짜 데이터 알맹이 (너무 작으면 46바이트 맞추려고 쓰레기값 채움) |
| **FCS (CRC-32)** | 4 Bytes | "오다가 상자 찌그러진 데 없지?" 하고 무결성 계산하는 꼬리표 |

#### 한줄 요약

- 머리엔 MAC 주소와 이더타입을 달고, 몸통엔 IP 데이터를 담고, 꼬리엔 에러 검출용 FCS를 단 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프레임 캡슐화(Frame Encapsulation)**: PC 랜카드가 쌩 데이터 앞뒤로 MAC 주소랑 꼬리표(FCS)를 덕지덕지 발라서 프레임이라는 택배 상자로 포장하는 거다.
- **FCS 오류 검증(FCS Error Validation)**: 받는 쪽 랜카드가 꼬리표 수학 공식(CRC-32)을 다시 풀어보고, 답이 틀리면 구겨진 걸로 간주해 칼같이 드롭(Drop)시키는 거다.

</details>

```text
[ 스위칭 및 프레임 캡슐화 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. [송신 PC] 캡슐화          │
│ (MAC + Payload + FCS 포장)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [L2 스위치] MAC 룩업      │
│ (목적지 MAC 보고 포트 결정)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [L2 스위치] 포워딩        │
│ (해당 포트로 무지성 발사!)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [수신 PC] FCS 오류 검증   │
│ (찌그러졌으면 버리고, 정상이면 뜯음)│
└──────────────────────────────┘
```

### 동작 원리

1. 프레임 캡슐화: 랜카드(NIC)가 MAC 헤더와 에러 검출 꼬리표(FCS)를 붙여서 랜선으로 쏨.
2. 스위치 목적지 MAC 조회: 스위치가 목적지 MAC을 MAC 테이블에서 검색함.
3. 출력 포트 중계: 매핑된 물리 포트로 프레임을 기계적으로 쏴버림.
4. 수신 NIC 오류 검증: CRC-32 공식을 다시 계산해서 FCS랑 대조해 보고, 에러면 버림.

#### 한줄 요약

- 포장해서 쏘면 스위치가 주소(MAC) 보고 던져주고, 받는 놈이 에러(FCS) 없으면 까먹는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Ethernet II (DIX 2.0)**: 2바이트 공간을 "안에 든 프로토콜 이름표(EtherType)"로 쿨하게 써서 전 세계 인터넷을 평정한 실전 상용 표준 규격이다.
- **IEEE 802.3 LLC**: 2바이트 공간을 "데이터 길이(Length)"로 쓰고, 프로토콜 이름표는 억지로 LLC 헤더를 뒤에 또 달아서 오버헤드만 늘려놓은 고지식한 학술 표준이다.

</details>

| 비교 항목 | **Ethernet II (상용 끝판왕)** | **IEEE 802.3 LLC (학자들 똥고집)** |
|:---|:---|:---|
| 2바이트 필드 용도 | 0x0600 이상: **EtherType** (내용물 이름표) | 0x05DC 이하: **Length** (데이터 길이) |
| 프로토콜 식별법 | 헤더에 있는 EtherType으로 한 방에 까봄 | LLC/SNAP 헤더를 뒤에 또 붙여서 까봄 |
| 헤더 오버헤드 | **14 Bytes** (심플하고 깔끔함) | **22 Bytes** (오버헤드 덕지덕지 늘어남) |
| 주 활용 분야 | 우리가 쓰는 **TCP/IP 인터넷 트래픽 99%** | 스위치끼리 통신하는 **STP, CDP 제어 패킷** 한정 |

#### 한줄 요약

- 99%의 인터넷은 가벼운 Ethernet II를 쓰고, 스위치끼리 노가리 깔 때만 무거운 IEEE 802.3 LLC를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **점보 프레임(Jumbo Frame)**: 1500바이트씩 잘게 쪼개 보내면 CPU가 힘들어 죽으니까, 아예 한 번에 9000바이트짜리 거대한 상자로 묶어 보내는 네트워크 튜닝이다.
- **VLAN 태그(802.1Q Tag)**: 스위치 트렁크 포트를 지날 때 "얘는 영업부 트래픽이야" 하고 출발지 MAC 바로 뒤에 4바이트짜리 꼬리표(VLAN ID)를 억지로 쑤셔 넣는 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프레임 중간에 **VLAN 태그 4바이트**를 쑤셔 넣었더니 제한 넘어서 프레임 깨짐 | 스위치 포트에 살짝 큰 사이즈 허용하는 **802.1Q Baby Giant 설정** | 뚱뚱해진 태그 프레임도 드롭 없이 무사통과 |
| 1500바이트씩 잘게 썰어 대량으로 보냈더니 **서버 CPU가 인터럽트 걸려 뻗음** | 스위치랑 서버 랜카드 둘 다 **점보 프레임(9000바이트) 활성화** | CPU 노가다(인터럽트) 줄어들고 대용량 전송 효율 떡상 |
| 랜선 구겨지거나 광케이블 불량 나서 0과 1이 비틀리며 **FCS 에러 속출함** | 스위치에서 CRC 에러 카운터 오르는 포트 찾아 **물리적 케이블 교체** | 피지컬(L1) 에러 해결 및 프레임 패킷 드롭 원천 차단 |

#### 한줄 요약

- 스위치 넘어갈 때 태그(VLAN) 붙는 거 조심하고, 전송량 빡세면 점보 프레임(9000)으로 파이프를 키워라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **경로 MTU 정합성(Path MTU Alignment)**: 출발지 PC부터 도착지 서버까지 중간에 거치는 모든 스위치와 라우터의 택배 상자 허용 크기(MTU)를 칼같이 똑같이 맞춰야 안 터진다는 실무 진리다.

</details>

- VLAN 태그 구간은 **경로 MTU 정합성**을 엄격히 맞추고 물리적 CRC 오류를 철저히 감시하는 기조 확립함

#### 한줄 요약

- 택배 상자 크기(MTU)는 중간 경로까지 전부 똑같이 세팅해야 중간에 상자가 터지는 불상사를 막을 수 있다.
