## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **이더넷 프레임(Ethernet Frame)**: 데이터링크 계층(OSI L2)에서 네트워크 계층(L3)의 패킷을 캡슐화하여 로컬 네트워크 세그먼트 내에서 신뢰성 있게 전송하기 위한 표준 프로토콜 데이터 단위(PDU).
- **프레임 검사 시퀀스(Frame Check Sequence, FCS)**: 프레임 전송 중 발생한 비트 오류를 검출하기 위해 트레일러에 부착하는 32비트 CRC-32 체크섬 필드.

</details>

- 정의/개념: L2 데이터링크 계층에서 송수신 호스트의 MAC 주소, 상위 계층 프로토콜 식별자(EtherType) 및 오류 검출용 **FCS(CRC-32)** 를 캡슐화한 표준 전송 프레임
- 배경/필요성: 물리 계층의 비트 스트림으로부터 프레임 경계 식별(동기화), L2 물리 주소 기반 포워딩 및 전송 중 비트 반전 결함 검출 요구

#### 한줄 요약
- MAC 주소와 EtherType 및 FCS를 캡슐화하여 로컬 네트워크 전송과 비트 오류를 검증하는 L2 PDU다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **프리앰블(Preamble) 및 SFD(Start Frame Delimiter)**: 수신 NIC의 클록 동기화를 유도하는 7바이트 프리앰블(`10101010` 반복)과 실제 프레임의 시작을 알리는 1바이트 SFD(`10101011`).
- **최소 프레임 크기(Minimum Frame Size)**: CSMA/CD 반이중 충돌 검출 환경에서 전송 지연 시간 내에 충돌을 감지하기 위해 규정된 64바이트(헤더 18B + 페이로드 최소 46B) 제한.

</details>

- **Preamble 및 SFD** 를 통한 물리 계층 비트 동기화 및 프레임 시작 경계 명확화
- 출발지/목적지 48비트 MAC 주소 조회를 통한 L2 스위치 하드웨어 포워딩 지원
- **FCS (CRC-32)** 검증을 통해 1비트 이상의 전송 오류 발생 시 즉각 프레임 폐기(Drop) 처리

#### 한줄 요약
- 프리앰블로 비트 동기화를 수행하고, MAC 주소로 포워딩하며, CRC-32로 프레임 무결성을 검증한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이더타입(EtherType)**: 상위 계층에 캡슐화된 프로토콜(IPv4: `0x0800`, ARP: `0x0806`, IPv6: `0x86DD`, VLAN: `0x8100`)을 식별하는 2바이트 필드.

</details>

```text
[ 이더넷 프레임 (Ethernet II) 헤더 구조 ]

 ┌──────────┬─────┬────────────┬────────────┬───────────┬──────────────────────┬─────────┐
 │ Preamble │ SFD │ 목적지 MAC │ 출발지 MAC │ EtherType │   데이터 페이로드    │   FCS   │
 ├──────────┼─────┼────────────┼────────────┼───────────┼──────────────────────┼─────────┤
 │ 7 Bytes  │ 1 B │  6 Bytes   │  6 Bytes   │  2 Bytes  │ 46 ~ 1500 Bytes (IP) │ 4 Bytes │
 └──────────┴─────┴────────────┴────────────┴───────────┴──────────────────────┴─────────┘
 (물리 동기화) ───▶ │ ◀────────────── 14바이트 L2 헤더 ─────────────▶ │ (트레일러)
```

선의 의미: 8바이트 동기화 필드, 14바이트 L2 헤더, 46~1500바이트 페이로드, 4바이트 FCS 트레일러의 배치 관계

| 구성요소 | 바이트 크기 | 책임 |
|:---|:---|:---|
| **Preamble + SFD** | 7 + 1 Bytes | 수신 인터페이스와의 클록 동기화 수립 및 프레임 시작 바이트 경계 통보 |
| **목적지 / 출발지 MAC** | 각 6 Bytes | 프레임을 수신할 대상 NIC 주소 및 전송한 NIC의 48비트 물리 주소 |
| **EtherType** | 2 Bytes | 상위 계층 네트워크 프로토콜 유형(IPv4, ARP, 802.1Q 태그 등) 명시 |
| **데이터 페이로드** | 46 ~ 1500 Bytes | 상위 계층 PDU (46바이트 미만일 경우 패딩 바이트를 채워 최소 64B 충족) |
| **FCS (CRC-32)** | 4 Bytes | 전송 중 비트 손상 여부를 검출하기 위한 다항식 기반 에러 체크섬 |

#### 한줄 요약
- 동기화 필드, MAC 주소 헤더, EtherType, 데이터 페이로드 및 FCS 트레일러로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프레임 캡슐화(Frame Encapsulation)**: L3 IP 패킷에 L2 MAC 헤더와 L2 FCS 트레일러를 부착하여 물리 계층으로 전달하는 과정.

</details>

```text
1. L3 IP 패킷 수신 및 페이로드 크기 검증 (46B 미만 시 패딩 추가)
            │
            ▼
2. L2 캡슐화: 출발지/목적지 MAC 및 EtherType 헤더 + FCS 트레일러 부착
            │
            ▼
3. L2 스위치 포워딩: CAM 테이블 조회 후 대상 포트로 단일 전달
            │
            ▼
4. 수신 NIC 오류 검증: CRC-32 재계산 후 FCS 일치 확인
            │
            ├─ [CRC 일치 (정상)] ──▶ 5a. L2 헤더 제거(디캡슐화) 후 상위 IP 계층 전달
            └─ [CRC 불일치 (에러)] ─▶ 5b. 프레임 즉각 폐기(Silent Drop)
```

**동작 원리**

1. **캡슐화**: 송신 호스트의 NIC 드라이버가 IP 패킷 앞뒤에 L2 헤더와 CRC-32 체크섬을 생성하여 프레임 조립
2. **비트 송출**: 프리앰블과 SFD를 선두로 하여 물리 매체로 비트 신호 전송
3. **스위칭 중계**: 중간 L2 스위치가 목적지 MAC을 조회하여 해당 포트로 스위칭
4. **무결성 검사**: 수신 NIC 하드웨어가 수신된 비트열에 대해 CRC-32를 계산하여 FCS 필드와 비교
5. **디캡슐화**: 에러가 없을 경우 L2 헤더를 분리하고 EtherType에 정의된 상위 프로토콜(IPv4 등) 스택으로 전달

#### 한줄 요약
- 캡슐화 후 스위칭 포워딩을 거쳐 수신단에서 CRC-32 무결성 검증 후 디캡슐화한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Ethernet II (DIX 2.0)**: 전 세계 TCP/IP 인터넷 트래픽의 사실상 표준으로 사용되는 2바이트 EtherType 기반 프레임 포맷.
- **IEEE 802.3 LLC/SNAP**: 2바이트 필드를 Length로 사용하고, 상위 프로토콜 구분을 위해 LLC(Logical Link Control) 및 SNAP 헤더를 추가하는 표준 프레임 포맷.

</details>

| 비교 항목 | Ethernet II (DIX 2.0) | IEEE 802.3 with LLC/SNAP |
|:---|:---|:---|
| **2바이트 필드 정의** | `0x0600` 이상: **EtherType** (프로토콜 식별) | `0x05DC` 이하: **Length** (데이터 바이트 길이) |
| **프로토콜 다중화** | 헤더의 EtherType 필드를 통해 직접 식별 | 별도의 8바이트 LLC/SNAP 헤더를 페이로드에 삽입 |
| **헤더 오버헤드** | **14 Bytes** (L2 Header 단독) | **22 Bytes** (L2 Header 14B + LLC/SNAP 8B) |
| **주요 적용 영역** | **TCP/IP 일반 데이터 트래픽의 99%** | **STP(BPDU), CDP, DTP** 등 L2 제어 프로토콜 |

#### 한줄 요약
- 일반 데이터 전송에는 Ethernet II를 사용하고, 스위치 제어 프로토콜에는 IEEE 802.3 LLC를 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **점보 프레임(Jumbo Frame)**: 표준 MTU(1500바이트)보다 큰 최대 9000바이트 페이로드를 전송하여 서버 CPU 인터럽트 횟수를 대폭 줄이는 기술.
- **802.1Q VLAN 태그**: VLAN 구분을 위해 이더넷 프레임의 출발지 MAC 뒤에 삽입되는 4바이트 태그(TPID `0x8100` + TCI).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 4바이트 VLAN 태그(`802.1Q`) 삽입으로 프레임 크기 초과(1522B) 및 드롭 | 스위치 포트에 **Baby Giant / 802.1Q 프레임 허용 MTU(1522B 이상)** 적용 | 태그가 부착된 트렁크 프레임의 무손실 정상 포워딩 |
| 대규모 스토리지(iSCSI/NFS) 전송 시 프레임 분할로 인한 서버 CPU 과부하 | 스위치 및 서버 NIC 전 구간에 **점보 프레임(Jumbo Frame, 9000B)** 활성화 | 패킷 처리 오버헤드 및 CPU 인터럽트 횟수 대폭 감소 |
| 케이블 노후화 및 신호 감쇄로 인한 물리 계층 **CRC/FCS 에러 다발** | 스위치 포트별 **CRC 에러 카운터 모니터링 및 불량 케이블 교체** | L2 레벨 프레임 유실 방지 및 재전송 부하 해소 |

#### 한줄 요약
- 802.1Q 태그 크기 보정, 점보 프레임(9000B) 활성화 및 물리 케이블 CRC 모니터링으로 전송 효율을 극대화한다.

## Ⅶ. 결론

- 로컬 네트워크의 기본 전송 단위인 **이더넷 프레임**의 처리 성능을 최적화하기 위해 데이터 경로 전반에 **Ethernet II** 표준을 적용하고, 스토리지 및 백본 구간에는 **점보 프레임**과 경로 MTU 일관성 설계를 수립하여 CPU 오버헤드를 줄이고 데이터 무결성을 보장

#### 한줄 요약
- Ethernet II 프레임 규격과 점보 프레임 설계를 통해 고성능·저지연 L2 스위칭 인프라를 구축한다.
