## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **이더넷 프레임(Ethernet Frame)**: 주소•상위 데이터•검사값을 묶어 전달하는 데이터링크 계층 전송 단위이다.
- **매체 접근 제어 주소(Media Access Control Address, MAC 주소)**: 같은 링크에서 송신•수신 인터페이스를 식별하는 주소이다.

</details>

- 정의/개념: **이더넷 프레임**은 송수신 **MAC 주소**•상위 데이터•오류 검사값을 캡슐화한 전송 단위이다.
- 배경/필요성: 연속 비트 신호만으로는 경계•수신자•오류를 식별할 수 없다.

#### 한줄 요약

- 연속된 신호에 시작•주소•내용•검사표를 붙여 하나의 운송 봉투로 구분한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **프리앰블(Preamble)**: 수신 클록을 맞추는 반복 비트 패턴이다.
- **프레임 시작 구분자(Start Frame Delimiter, SFD)**: 프레임 시작 경계를 표시하는 비트 패턴이다.
- **프레임 검사 시퀀스(Frame Check Sequence, FCS)**: 프레임의 비트 오류를 검출하는 검사값이다.

</details>

- **프리앰블**은 수신 클록을 맞추고 **SFD**는 프레임 시작을 표시한다.
- 목적지 **MAC 주소**는 링크의 수신 인터페이스를 식별한다.
- **FCS**는 비트 오류를 검출하지만 정정하지는 않는다.

#### 한줄 요약

- 검사값이 틀린 프레임은 버리고 재전송은 필요한 상위 계층이 맡는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **이더타입(EtherType)**: 이더넷 II 프레임의 상위 프로토콜을 값으로 표시하는 필드이다.
- **논리 링크 제어(Logical Link Control, LLC)**: IEEE 802.3 길이 필드 뒤에서 상위 서비스를 구분하는 부계층이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: 다항식 연산으로 전송 오류를 검출하는 방식이다.
- **32비트 순환 중복 검사(Cyclic Redundancy Check-32, CRC-32)**: FCS에 쓰이는 32비트 검사 방식이다.
- **전기전자공학자협회 802.3(Institute of Electrical and Electronics Engineers 802.3, IEEE 802.3)**: 이더넷의 매체 접근 방식과 프레임 형식을 규정하는 표준이다.

</details>

```text
이더넷 프레임 필드 순서
├── 프리앰블•SFD
├── MAC 주소
├── 유형•길이
├── 페이로드•패드
└── FCS
```

선의 의미: 선은 하나의 이더넷 프레임 안에서 동기•경계, 링크 주소, 상위 형식, 실제 데이터와 오류 검사 필드가 나란히 결합되는 정적 프레임 레이아웃을 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 프리앰블•SFD | **프리앰블**로 클록 동기, **SFD**로 시작 표시 |
| MAC 주소 | **MAC 주소**로 수신•송신 인터페이스 식별 |
| 유형•길이 | **이더타입** 또는 **IEEE 802.3** 길이로 상위 형식 표시 |
| 페이로드•패드 | 상위 자료•최소 길이 보충 |
| FCS | **CRC-32**의 **CRC** 연산으로 비트 오류 검출 |

#### 한줄 요약

- 앞의 주소와 내용 종류로 전달•해석하고 뒤의 검사표로 운송 중 손상됐는지 확인한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **네트워크 인터페이스 카드(Network Interface Card, NIC)**: 프레임을 직렬화•송수신하고 목적지 주소와 FCS를 검사하는 네트워크 인터페이스 장치이다.
- **프레임 전송**: 주소•유형•자료•FCS 필드를 직렬화하여 링크로 내보내는 절차이다.
- **MAC 주소 조회**: 목적지 MAC 주소를 포워딩 정보와 비교해 출력 포트를 찾는 절차이다.
- **출력 포트 중계**: 조회한 목적지 인터페이스 방향으로 프레임을 전달하는 절차이다.
- **FCS 오류 검증**: 수신 프레임의 CRC 결과를 FCS와 비교하여 오류 여부를 판정하는 절차이다.

</details>

```text
상위 계층 데이터
       |
       v
1. 프레임 전송
       |
       v
2. MAC 주소 조회
       |
       v
3. 출력 포트 중계
       |
       v
4. FCS 오류 검증
       |
       +-- CRC 불일치 ---- 프레임 폐기
       |
       `-- CRC 일치 ------ 상위 프로토콜 전달
```

### 동작 원리

**NIC**는 다음 절차로 프레임을 송수신한다.

1. **프레임 전송**: 주소•유형•자료•FCS을 직렬화한다.
2. **MAC 주소 조회**: 목적지 주소로 출력 포트를 결정한다.
3. **출력 포트 중계**: 목적지 인터페이스로 프레임을 전달한다.
4. **FCS 오류 검증**: CRC 불일치 프레임을 폐기한다.

#### 한줄 요약

- 봉투 시작을 찾고 주소로 포트를 선택한 뒤 오류 검사를 통과한 내용만 담당 프로토콜에 넘긴다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **이더넷 II(Ethernet II)**: 유형 필드를 상위 프로토콜 식별값으로 읽는 프레임 형식이다.
- **IEEE 802.3 LLC**: 공통 필드를 데이터 길이로 읽고 LLC로 서비스를 구분하는 형식이다.
- **인터넷 프로토콜(Internet Protocol, IP)**: 이더넷 페이로드에 캡슐화되어 네트워크 간 패킷 전달을 담당하는 프로토콜이다.

</details>

| 이더넷 프레임 형식 | **이더넷 II** | **IEEE 802.3 LLC** |
|:---|:---|:---|
| 적용 기준 | 일반 **IP** 기반 이더넷 통신 | IEEE 802 계열 **LLC** 서비스 |
| 핵심 특징 | **이더타입**으로 상위 프로토콜 표시 | 길이 뒤 LLC로 상위 서비스 표시 |
| 한계 | 이더타입 오해석•비호환 | 길이•LLC 헤더 오해석 |

> 요약: 유형•길이 필드값으로 프레임 형식 판별이 핵심이다.

#### 한줄 요약

- 같은 칸을 내용 종류로 읽으면 이더넷 II, 길이로 읽으면 IEEE 802.3이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최대 전송 단위(Maximum Transmission Unit, MTU)**: 링크가 운반할 수 있는 최대 상위 데이터 크기이다.
- **점보 프레임(Jumbo Frame)**: 표준 MTU보다 큰 페이로드를 지원하는 이더넷 프레임이다.
- **가상 근거리 통신망 태그(Virtual Local Area Network Tag, VLAN 태그)**: IEEE 802.1Q가 프레임에 추가하는 VLAN 식별•우선순위 정보이다.
- **전기전자공학자협회 802.1Q(Institute of Electrical and Electronics Engineers 802.1Q, IEEE 802.1Q)**: 이더넷 프레임에 VLAN 식별자와 우선순위 정보를 삽입하는 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경로 **MTU** 불일치 | 전체 장비의 허용 크기 대조 | 중간 프레임 폐기 방지 |
| **FCS** 오류 증가 | 케이블•광모듈•포트 통계 점검 | 물리 결함 신속 탐지 |
| **이더타입** 오해석 | 프레임 형식•상위 값 확인 | 프로토콜 전달 정확성 확보 |
| **IEEE 802.1Q**의 **VLAN 태그** 삽입 | 태그를 포함한 프레임 크기 대조 | 크기 초과 폐기 방지 |

#### 한줄 요약

- 큰 프레임을 쓰는 모든 장비의 통과 크기가 같아야 중간 장비에서 프레임이 버려지지 않는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **경로 MTU 일치**: 송수신 전 구간이 같은 최대 프레임 크기를 지원하도록 맞추는 조건이다.

</details>

- **경로 MTU 일치**가 보장되면 **점보 프레임**을 사용하고 그렇지 않으면 표준 크기를 선택한다.

#### 한줄 요약

- 수신 주소와 자료 종류, 검사값을 확인하면 프레임 전달 장애 지점을 찾을 수 있다.
