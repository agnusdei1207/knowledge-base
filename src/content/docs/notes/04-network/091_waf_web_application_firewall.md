## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **WAF (웹 애플리케이션 방화벽)**: 기존 방화벽이 항구에서 "너 배(IP) 어디서 왔어?"만 묻고 화물칸은 안 열어보는 바보라면, WAF는 화물칸(HTTP 페이로드)을 샅샅이 뜯어서 그 안에 폭탄(SQL Injection, XSS)이 있는지 팩트 체크하는 L7 웹 전용 세관이다.

</details>

- 정의: **WAF**는 웹 트래픽(HTTP/HTTPS)의 페이로드와 문맥을 심층 분석하여, 기존 방화벽이 못 잡는 SQL 인젝션, XSS 등 응용 계층(L7) 공격을 팩트로 탐지하고 차단하는 웹 전용 보안 시스템이다.
- 배경: 해커들이 옛날 방화벽(L3/L4)이 포트 80(웹)이랑 443(HTTPS)은 무조건 열어둔다는 점을 악용해서, **정상적인 웹 접속인 척 껍데기를 쓰고 악성 코드를 날리기 시작해서 뚫려버렸다.**

#### 한줄 요약

- 겉보기엔 정상 웹 접속이지만 속에 독을 품고 들어오는 해커들의 수작을, 화물칸 다 까뒤집어서 잡아내는 전용 방화벽이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 패치 (Virtual Patch)**: 개발자가 밤새워서 소스코드 고치고 서버 재시작할 필요 없이, WAF에 "이 패턴 막아!" 하고 한 줄 치면 즉시 팩트 방어막이 쳐지는 개꿀 기능이다.
- **정규화 (Normalization)**: 해커가 WAF 눈속임하려고 악성코드를 Base64나 URL 인코딩으로 베베 꼬아서 보내면, 팩트 체크를 위해 원래 평문으로 다 풀어헤치는 껍질 까기 기술이다.

</details>

- **팩트 체크 (HTTP 문맥 분석)**: URL, Header, Body를 종합적으로 해석해서 단순 텍스트가 아니라 이게 정상적인 요청인지 공격인지 팩트로 판별한다.
- **코드 안 고쳐도 1차 방어 (가상 패치)**: 제로데이 취약점이 터졌을 때 코드를 수정하기 전이라도, WAF에서 즉시 차단 룰을 올려서 임시 방어막을 칠 수 있다.

#### 한줄 요약

- 개발자가 코드 고칠 시간 벌어주고, 해커가 코드를 꼬아서 보내도 쌩얼로 만들어서 두들겨 패는 보안 장비다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **역방향 대리자 (Reverse Proxy)**: 해커가 우리 메인 웹서버랑 다이렉트로 말 섞지 못하게, 중간에 WAF가 끼어들어 트래픽을 대신 받고 팩트 검사한 다음 깨끗한 것만 토스해 주는 방패 구조다.
- **TLS 종단 (SSL Offloading)**: 암호화된 트래픽(HTTPS)은 WAF도 못 읽으니까, WAF에서 일단 암호를 팩트로 풀고 까본 다음, 이상 없으면 다시 포장해서 넘겨주는 검문소다.

</details>

```text
[ WAF 역방향 대리자 팩트 폭행 구조 ]

[ 1. 해커 / 클라이언트 ] ── (웹사이트 해킹하려고 HTTPS로 SQL Injection 쏨)
      │
      ▼
[ 2. TLS 종단기 (WAF 전면) ] ── (잠깐! 암호화 풀어서 화물칸 열어볼게)
      │
      ▼
[ 3. HTTP 해석/정규화기 ] ── (해커가 꼬아놓은 인코딩 평문으로 다 풀고 팩트 체크 준비)
      │
      ▼
[ 4. WAF 정책 엔진 ] ── (시그니처 비교. 어? 이거 해킹 공격이네? 컷트!)
      │
      ▼ (정상 트래픽일 경우만 통과)
[ 5. 원본 웹 서버 ] ── (WAF가 세탁해 준 깨끗한 트래픽만 받아서 장사함)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **TLS 종단기** | 암호화된 HTTPS 트래픽 **자물쇠 부수고 내용물 꺼내는 검문소** | SSL Offloading |
| **해석/정규화기** | 해커가 눈속임으로 꼬아놓은 코드 **다 풀어서 평문 팩트로 쌩얼 드러냄** | Normalizer |
| **WAF 정책 엔진** | 블랙리스트/화이트리스트 룰 들이밀어서 **공격 여부 팩트 체크하는 뇌** | Policy Engine |
| **원본 웹 서버** | 해커한테 IP 숨기고, **WAF가 걸러준 찐 고객만 상대하는 메인 서버** | Origin Server |
| **관측•튜닝기** | WAF가 오탐(정상 손님 차단) 안 내게 **로그 보면서 룰 깎는 노가다 툴** | Tuning Engine |

#### 한줄 요약

- 암호 풀고 $\to$ 꼬인 글자 펴고 $\to$ 해킹인지 팩트 체크하고 $\to$ 깨끗한 놈만 진짜 서버로 넘겨준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **서명 매칭 (Signature Matching)**: WAF가 수만 가지 해킹 패턴(시그니처)이 적힌 블랙리스트 수첩을 들고, 들어오는 트래픽이랑 한 줄 한 줄 비교해서 걸러내는 팩트 검사다.

</details>

```text
[ WAF L7 페이로드 팩트 체크 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [TLS 암호 복호화 (종단)]  │
│ (WAF: 암호 풀고 내용물(Payload) 까서 평문으로 바꿈)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [HTTP 요청 디코딩/정규화] │
│ (WAF: URL 꼬아놓은 거 싹 다 풀어서 원래 글자로 세탁함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [공격 시그니처 팩트 체크] │
│ (WAF: 룰북이랑 비교. 'SELECT * FROM' 떴다! 공격 컷트)
└──────────────┬───────────────┘
               ▼ (정상 판정 시)
┌──────────────────────────────┐
│ 4. [허용 트래픽 역방향 중계] │
│ (WAF: 깨끗한 트래픽만 원본 서버(Origin)로 대신 토스해 줌)
└──────────────────────────────┘
```

### 동작 원리

1. TLS 요청 복호화: WAF가 서버 대신 SSL 인증서 들고 HTTPS 암호를 풀어버림.
2. HTTP 요청 정규화: 해커가 WAF를 바보 만들려고 인코딩 떡칠한 걸 싹 다 평문으로 디코딩함.
3. 공격 문맥 판정: 정규식이나 AI 엔진 돌려서 SQL 인젝션인지 XSS 공격인지 팩트로 잡아냄.
4. 허용 요청 중계: 정상 손님이면 다시 포장해서 우리 웹서버한테 안전하게 쏴줌.

#### 한줄 요약

- 껍질 까고 $\to$ 씻기고 $\to$ 불순물(해킹) 걸러내고 $\to$ 알맹이만 서버에 보낸다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **네트워크 방화벽 (L3/L4)**: IP랑 포트 번호만 보고 열어줄지 말지 결정하는 무식한 1차원적 문지기다.
- **시큐어 코딩 (응용 코드 검증)**: 장비에 의존하는 게 아니라 개발자가 애초에 코드를 짤 때 해킹 못 하게 팩트로 방탄 코드를 짜는 근본 방어법이다.

</details>

| 보안 통제 지점 비교 | **네트워크 방화벽 (L3/L4)** | **WAF (L7 웹 방화벽)** | **시큐어 코딩 (응용 코드)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **건물 입구에서 "신분증"만 검사함** | **가방 다 열어서 "흉기" 있는지 팩트 체크함** | **직원이 돈통 안 털게 애초에 CCTV 달고 통제함** |
| 통제 계층 | L3 (IP), L4 (Port, TCP 상태) | L7 (HTTP 페이로드 전체 영역) | 애플리케이션 비즈니스 로직 내부 |
| 핵심 방어 대상 | 디도스 방어, 불법 IP 접근 차단 | SQL Injection, XSS, 웹 무차별 대입 | 권한 상승 우회, 결제 금액 조작 등 논리 공격 |
| 치명적 한계 | 80/443(웹) 포트 열어두면 **해킹 패킷도 정상인 줄 알고 걍 패스시킴** | 해킹 패턴은 다 잡지만, **정상 로그인 후 포인트 조작 같은 논리적 오류는 못 잡음** | 개발자 실력 오지게 타서 **검증 하나 빼먹으면 다 뚫림** |

#### 한줄 요약

- 방화벽은 IP를 거르고, WAF는 웹 해킹을 거르고, 시큐어 코딩은 서비스 로직 자체를 철통 방어한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오탐 (False Positive)**: 정상 고객이 게시판에 글 좀 길게 썼다고 WAF가 XSS 공격으로 오해해서 계정 차단해 버리는 최악의 팀킬이다. WAF 운영의 핵심은 이 억울한 오탐을 줄이는 노가다 튜닝이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 제로데이 취약점 터져서 **서버 패치할 때까지 무방비로 뚫림** | 개발자가 소스코드 고치고 서버 리부팅할 때까지 하루 이틀 공백이 생김 | WAF에 악용 패턴 **'가상 패치(Virtual Patch)' 룰 즉시 박아서 당장 컷트함** | 소스코드 수정 전까지 1차 방패 쳐서 서비스 털림 모면 |
| WAF 켰더니 **정상 고객 로그인도 공격으로 차단당함 (오탐)** | WAF 룰을 너무 빡세게(기본값) 걸어서 찐 고객의 억울한 트래픽도 팩트 체크 없이 다 자름 | 적용 초기에 **차단 말고 모니터링(Audit) 모드로 두고, 로그 보면서 '예외 튜닝' 빡세게 돌림** | 찐 고객 팀킬(오탐) 방지 및 공격만 정밀 타격하는 팩트 룰 완성 |
| WAF 달고 났더니 **웹사이트 로딩 속도 엄청 느려짐** | WAF가 모든 트래픽 암호화/복호화(TLS) 다 하려니까 CPU 터져서 딜레이 옴 | SSL 인증서 처리를 WAF가 아닌 **전용 L4/L7 로드밸런서 장비로 분리(SSL Offloading)함** | WAF 부하 확 줄이고 체감 속도와 쾌적함 확보 |

#### 한줄 요약

- 뚫리기 전에 가상 패치 바르고, 찐 고객 차단 안 되게 룰 깎고, WAF 버벅대면 암호 해독 작업은 남한테 넘겨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 웹 위협의 L7 응용 계층 은닉성을 완벽히 제거하기 위해, **L3/L4 방화벽 경계**, **WAF의 심층 페이로드 통제 및 가상 패치**, 그리고 근본적인 **시큐어 코딩**을 연계한 심층 다단 방어 기조 확립함

#### 한줄 요약

- WAF는 웹사이트 대문에 세워둔 떡대 좋은 기도비닉 장비지만, 이거 하나 믿고 개발자가 시큐어 코딩 대충 하면 결국 뒤통수 맞는다.
