## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **WAF(Web Application Firewall)**: L3/L4 계층의 IP/Port만을 검사하는 전통적 방화벽과 달리, L7 응용 계층의 HTTP/HTTPS 요청 및 응답 페이로드(URL, Method, Header, Cookie, Body)를 심층 분석하여 웹 취약점 공격을 탐지·차단하는 특화 보안 시스템.
- **OWASP Top 10**: 웹 애플리케이션에서 가장 빈번하고 치명적인 10대 보안 위협(인젝션, 취약한 인증, XSS, SSRF, 역직렬화 결함 등)을 정리한 글로벌 표준 가이드라인.

</details>

- 정의/개념: 인바운드 HTTP/HTTPS 트래픽의 URI, 쿼리 스트링, 헤더, POST 바디를 디코딩/정규화(Normalization)하여 **OWASP Top 10 기반의 악성 페이로드(SQLi, XSS 등)** 를 탐지·차단하고, 코드 수정 전 긴급 방어를 지원하는 **L7 웹 보안 프록시**
- 배경/필요성: L3/L4 네트워크 방화벽이 표준 웹 서비스 포트(HTTP 80, HTTPS 443)를 전면 개방해야 하는 구조적 한계를 악용하여, 정상적인 웹 요청으로 위장해 침투하는 애플리케이션 계층 공격을 방어할 요구

#### 한줄 요약
- L7 HTTP/HTTPS 트래픽의 페이로드를 정규화 및 심층 검사하여 OWASP Top 10 공격을 차단한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 패치(Virtual Patching)**: 애플리케이션 소스코드의 취약점을 개발자가 직접 수정하고 재배포하기 전, WAF 단에서 해당 취약점을 악용하는 특정 공격 패턴을 정합 차단하는 보안 규칙을 긴급 적용하여 제로데이 공격을 임시 무력화하는 기법.
- **HTTP 정규화(Normalization)**: 공격자가 WAF 시그니처 탐지를 우회하기 위해 적용한 URL 인코딩, Base64, 유니코드, 중복 슬래시 등을 표준 평문(Canonical Form)으로 역변환하는 전처리 과정.

</details>

- **L7 심층 페이로드 분석**: HTTP Header, Cookie, Form Data, JSON/XML 파싱 및 문맥(Context) 기반 공격 판단
- **가상 패치(Virtual Patching) 기반 제로데이 긴급 대응**: 운영 중인 백엔드 서비스의 무중단 상태에서 WAF 룰 적용만으로 즉각적인 취약점 방어선 구축
- **다양한 구축 토폴로지 지원**: 리버스 프록시(Reverse Proxy), 인라인(Inline), 미러링/SPAN(Out-of-Band), 클라우드 SaaS WAF 제공

#### 한줄 요약
- L7 페이로드 심층 검사, 제로데이 가상 패치, 정규화 기반 우회 차단을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **리버스 프록시(Reverse Proxy)**: 클라이언트와 웹 서버 사이에 위치하여 클라이언트의 요청을 대신 수신하고, SSL 복호화 및 보안 검사를 완료한 정상 트래픽만을 백엔드 웹 서버로 중계하는 아키텍처.
- **SSL 가속 및 오프로딩(SSL Offloading)**: 암호화된 HTTPS 트래픽의 연산 부하를 WAF 또는 전용 하드웨어 가속기에서 전담 처리하여 백엔드 서버의 리소스를 보존하는 메커니즘.

</details>

```text
[ 외부 클라이언트 / 공격자 ] ──▶ (HTTPS 요청 인입: Port 443)
                                          │
                                          ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ WAF 시스템 (Reverse Proxy 모드) ]                                      │
│  ├─ 1. SSL/TLS 종단 및 복호화 (SSL Offloading) ── (평문 HTTP 페이로드 추출)│
│  ├─ 2. HTTP 디코딩 및 정규화기 (Normalization) ── (URL/Base64/Unicode 디코딩)│
│  ├─ 3. 정책 분석 엔진 (시그니처 / Positive-Negative 모델 / AI 이상 탐지)  │
│  └─ 4. 응답 데이터 마스킹 (DLP: 주민번호, 신용카드 번호 유출 차단)        │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (검증 완료된 정상 트래픽만 내부 중계)
                                     ▼
                      [ 백엔드 웹/WAS/DB 인프라 ]
```

선의 의미: 인입되는 암호화 웹 트래픽이 WAF에서 복호화 및 정규화 과정을 거쳐 정책 검사를 통과한 후 백엔드 웹 서버로 안전하게 전달되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **SSL/TLS 종단 모듈** | 인증서 기반 HTTPS 세션 종단, SSL 복호화 및 가속(Crypto Offloading) | 암복호화 처리 |
| **정규화 엔진** | URL-Encoding, Hex, Unicode 등 우회 인코딩을 표준 평문으로 변환 | Normalization |
| **룰 분석 엔진** | OWASP Top 10 시그니처 매칭, 정규표현식 검사 및 레이트 리미팅 | Policy Engine |
| **DLP 마스킹 모듈** | 서버 응답(HTTP Response) 내의 개인정보 및 시스템 에러 메시지 은폐 | 정보 유출 방지 |
| **감사 로그 및 튜닝기** | 차단/허용 로그 기록, 오탐(False Positive) 분석 및 화이트리스트 튜닝 | Audit & Analytics |

#### 한줄 요약
- SSL 종단기, 정규화 엔진, 룰 정책 엔진, DLP 마스킹 모듈, 튜닝기가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Positive Security Model vs Negative Security Model**: 허용된 정상 요청 패턴만을 정의하고 나머지는 모두 차단하는 화이트리스트 방식과, 알려진 공격 패턴(시그니처)만을 정의하여 차단하는 블랙리스트 방식.

</details>

```text
1. 외부 클라이언트가 웹 애플리케이션으로 HTTPS 요청 전송 ➔ WAF 리버스 프록시 인입
            │
            ▼
2. WAF가 SSL 인증서를 통해 세션을 종단하고 암호화된 트래픽을 평문 HTTP로 복호화
            │
            ▼
3. HTTP 요청 헤더 및 파라미터의 다중 인코딩(URL/Hex/Base64)을 단일 표준 텍스트로 정규화
            │
            ▼
4. 시그니처 매칭(Negative) 및 허용 URL 규칙(Positive) 대조 ➔ 악성 패턴(SQLi/XSS) 검사
            │
            ├─ [공격 패턴 감지] ➔ 즉시 HTTP 403 Forbidden 응답 반환 및 IP 차단
            ▼
5. [정상 요청 판정] ➔ 백엔드 웹 서버(Origin)로 요청 포워딩 ➔ 응답 개인정보 마스킹 후 반환
```

**동작 원리**

1. **세션 복호화**: HTTPS 암호화 터널을 WAF 단에서 종단하여 L7 페이로드의 완전한 가시성 확보
2. **지능형 정규화**: 공격자의 난독화 기법을 해제하여 본래의 악성 스크립트 형태 도출
3. **복합 룰 평가**: 시그니처 기반 블랙리스트와 엄격한 파라미터 제약 화이트리스트 동시 적용
4. **선제적 차단**: 백엔드 서버 도달 전 WAF 인라인 상에서 세션을 즉각 리셋하고 경보 전송
5. **양방향 보호**: 인바운드 공격 차단뿐만 아니라 아웃바운드 응답 내 DB 에러 및 개인정보 필터링

#### 한줄 요약
- SSL 복호화, HTTP 정규화, 복합 정책 검사, 악성 요청 즉각 차단, 응답 개인정보 마스킹 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **네트워크 방화벽 vs WAF vs 시큐어 코딩**: 인프라 경계 L3/L4 제어, L7 웹 트래픽 전용 심층 검사, 소스코드 레벨 취약점 근본 제거의 비교.

</details>

| 비교 항목 | 네트워크 방화벽 (L3/L4) | 웹 방화벽 (WAF / L7) | 시큐어 코딩 (Secure Coding) |
|:---|:---|:---|:---|
| **통제 계층** | **L3 (IP), L4 (Port / TCP 플래그)** | **L7 (HTTP/HTTPS 페이로드 전 영역)** | **애플리케이션 소스코드 및 로직 계층** |
| **검사 대상** | 출발지/목적지 IP, 포트, 패킷 플래그 | **URI, Query, Header, Cookie, Body** | **변수 입력값, 비즈니스 로직, 메모리** |
| **방어 대상 공격** | IP Spoofing, 포트 스캔, SYN Flood | **SQL Injection, XSS, CSRF, 웹쉘** | **권한 상승, 로직 우회, 제로데이 결함** |
| **한계점** | 80/443 오픈 시 웹 공격 무방비 통과 | 복잡한 비즈니스 로직 결함 탐지 곤란 | 개발자 역량 의존 및 레거시 수정 곤란 |
| **주요 역할** | 네트워크 경계 1차 접근 통제 | **실시간 웹 공격 방어 및 가상 패치** | **소프트웨어 근본적 결함 원천 제거** |

#### 한줄 요약
- 네트워크 방화벽은 경계 L3/L4 통제, WAF는 L7 공격 실시간 방어, 시큐어 코딩은 소프트웨어 결함 원천 제거를 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오탐(False Positive) 및 감사 모드(Audit/Detection Only Mode)**: 정상 비즈니스 요청을 공격으로 오인하여 차단하는 사고를 방지하기 위해, WAF 초기 도입 시 차단 없이 로그만 적재하며 규칙을 튜닝하는 운영 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| WAF 신규 룰 배포 시 정상 사용자 요청을 공격으로 오인하여 차단하는 **오탐(False Positive) 발생** | **감사 모드(Detection Only) 2주 운영** 및 사용자 패턴 기반 **정밀 예외(Whitelisting) 튜닝** | 정상 서비스 가용성 100% 보장 및 오탐률 0.01% 이하 통제 |
| 신규 제로데이 취약점 공개 후 소스코드 패치 완료 시까지의 보안 방어 공백 | **WAF 가상 패치(Virtual Patching) 긴급 룰** 실시간 생성 및 즉시 배포 | 개발 및 배포 소요 기간 동안 제로데이 익스플로잇 선제적 무력화 |
| 대규모 HTTPS 웹 트래픽의 SSL 복호화 연산으로 인한 WAF 장비 CPU 고갈 및 응답 지연 | **하드웨어 가속 SSL Offloading L4/L7 스위치** 분리 또는 클라우드 SaaS WAF 전환 | WAF 장비 부하 분산 및 밀리초 단위 웹 응답 처리 성능 확보 |

#### 한줄 요약
- 감사 모드 튜닝으로 오탐을 방지하고, 가상 패치로 제로데이에 대응하며, SSL Offloading으로 부하를 최적화한다.

## Ⅶ. 결론

- 웹 기반 전자상거래 및 클라우드 API 서비스의 가용성과 기밀성을 확보하기 위해 **L7 WAF 역방향 프록시 아키텍처**를 필수 배치하되, 운영 안정성과 보안성을 극대화하기 위해 **지속적인 화이트리스트 예외 튜닝**, **긴급 가상 패치(Virtual Patching) 프로세스**, **SSL Offloading 하드웨어 가속** 및 **DevSecOps 시큐어 코딩**을 결합한 다계층 웹 보안 체계를 완성

#### 한줄 요약
- WAF의 L7 심층 검사와 가상 패치 및 시큐어 코딩을 통합하여 견고한 엔터프라이즈 웹 보안을 실현한다.
