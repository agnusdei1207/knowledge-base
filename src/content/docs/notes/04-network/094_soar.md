## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SOAR(Security Orchestration, Automation, and Response)**: SIEM, EDR, 방화벽, 위협 인텔리전스(TI) 등 이기종 보안 솔루션들을 API 기반으로 연계(Orchestration)하고, 정형화된 사고 대응 프로세스를 플레이북(Playbook)으로 자동 실행(Automation)하여 침해 사고 분석 및 차단 대응(Response) 시간을 단축하는 보안 운영 플랫폼 (Gartner 정의).
- **플레이북(Playbook / Runbook)**: 피싱 메일 차단, 악성 IP 방화벽 등록, 랜섬웨어 감염 호스트 네트워크 격리 등 특정 침해 유형별 표준 대응 절차(SOP)를 워크플로우 코드로 구현한 자동화 실행 시나리오.

</details>

- 정의/개념: 이기종 보안 장비의 API를 단일 워크플로우로 통합 제어하는 **보안 오케스트레이션(Orchestration)**, 반복적 분석·조사 작업을 수행하는 **보안 자동화(Automation)**, 사전 정의된 **플레이북 기반 인시던트 대응(Response)** 을 제공하는 **차세대 보안관제 운영 자동화 아키텍처**
- 배경/필요성: 일일 수만 건의 SIEM 경보를 수작업으로 분석하고 개별 장비에 수동 로그인하여 차단하는 과정에서 발생하는 심각한 분석가 피로도(Alert Fatigue), 대응 지연 및 휴먼 에러를 극복할 요구

#### 한줄 요약
- 이종 보안 도구를 API로 오케스트레이션하고 플레이북 기반으로 위협 탐지·분석·차단을 자동화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **휴먼 인 더 루프(Human-in-the-Loop, HITL)**: 위험도가 낮은 단순 스캔 차단은 100% 자동 실행하되, 핵심 비즈니스 서버 격리나 관리자 계정 잠금 등 파급력이 큰 고위험 조치는 관제 팀장의 승인(Approval)을 거쳐 집행하도록 분기하는 안전 제어 기법.
- **멱등성(Idempotency)**: 동일한 플레이북 차단 명령(예: `Block_IP_1.1.1.1`)이 네트워크 재시도로 인해 중복 수신되더라도 대상 방화벽에 단 1건의 규칙만 정합 적용되어 시스템 부작용이 발생하지 않는 특성.

</details>

- **이기종 API 표준화 오케스트레이션**: 방화벽, EDR, Active Directory, 이메일 게이트웨이의 상이한 명령어를 공통 커넥터(App)로 추상화
- **플레이북 기반 대응 표준화 및 시간 단축**: 사고 탐지부터 격리까지의 평균 대응 시간(MTTR)을 수 시간에서 수초 단위로 단축
- **조치 영향도 기반 반자동/전자동 제어 (HITL)**: 조치의 가역성(Reversibility)과 비즈니스 위험도에 따라 전자결재 승인 관문 분기

#### 한줄 요약
- 이종 API 오케스트레이션, 플레이북 기반 MTTR 단축, HITL 승인 분기 및 멱등성 보장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **앱 및 연동 어댑터(App & Integrations)**: Palo Alto Networks, CrowdStrike, VirusTotal 등 타사 보안 장비의 REST API를 호출하여 파라미터를 전달하고 응답을 파싱하는 플러그인 모듈.
- **케이스 관리(Case Management)**: 발생한 보안 인시던트의 조사 타임라인, 수집된 아티팩트(Artifact), 실행된 플레이북 로그, 감사 추적 데이터를 단일 티켓으로 생애주기 관리하는 모듈.

</details>

```text
[ SIEM / EDR / 이메일 보안 경보 인입 ]
                 │
                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ SOAR 플랫폼 코어 엔진 ]                                               │
│  ├─ 1. 위협 맥락 보강 (Enrichment Engine) ── (VirusTotal/자산 중요도 조회)│
│  ├─ 2. 플레이북 오케스트레이터 (Workflow Engine) ── (BPMN 기반 시나리오 실행)│
│  ├─ 3. 승인 관문 (Human-in-the-Loop) ────── (고위험 조치 관리자 승인 대기) │
│  └─ 4. 케이스 관리 및 감사 추적 (Case Management) ── (티켓 라이프사이클)   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (REST API 호출: JSON Payload)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 연동 어댑터 계층 (Security Tools Integration) ]                       │
│  ├─ 방화벽/WAF 커넥터 ──▶ (악성 IP/도메인 차단 룰 자동 주입)             │
│  ├─ EDR 에이전트 커넥터 ──▶ (엔드포인트 악성 프로세스 Kill 및 망 격리)      │
│  └─ 메일 게이트웨이 커넥터 ──▶ (전사 수신함 피싱 이메일 일괄 자동 영구 삭제)│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: SIEM 경보가 인입되면 SOAR가 위협 정보를 보강하고 플레이북에 따라 관리자 승인을 거쳐 각 보안 장비 API로 일괄 차단 조치를 집행하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **위협 맥락 보강기** | 인입된 IP, 도메인, 파일 해시를 TI 서비스와 내부 CMDB에서 자동 조회·주입 | Enrichment |
| **플레이북 엔진** | 조건문, 루프, API 호출, 승인 분기를 포함한 사고 대응 워크플로우 실행 | BPMN / Python |
| **승인/권한 관문** | 핵심 서버 격리 등 비즈니스 중단 위험이 있는 조치에 대해 관리자 결재 강제 | HITL Gateway |
| **연동 어댑터 (App)** | 이종 보안 벤더별 REST API 명세를 표준화하여 읽기/쓰기 액션 실행 | Plugin Hub |
| **케이스 관리 시스템** | 인시던트 티켓 생성, 증적 데이터 수집, 대응 이력 감사 로깅 및 보고서 생성 | Case Lifecycle |

#### 한줄 요약
- 맥락 보강기, 플레이북 엔진, HITL 승인 관문, 연동 어댑터, 케이스 관리 모듈이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보상 트랜잭션(Compensation Action)**: 다단계 자동 조치 수행 중 특정 단계 실패(Timeout/Error) 시, 앞서 실행된 차단 조치를 이전 정상 상태로 안전하게 롤백(Rollback)하는 복구 로직.

</details>

```text
1. SIEM에서 '악성 C&C 통신 의심' 고위험 인시던트가 SOAR 플랫폼으로 실시간 전달
            │
            ▼
2. SOAR가 외부 TI(VirusTotal) 악성 점수와 내부 자산 중요도(DB 서버 여부)를 자동 결합하여 맥락 보강
            │
            ▼
3. 'C&C 통신 대응 플레이북' 가동 ➔ 영향도 평가(단순 엔드포인트 vs 미션 크리티컬 코어 서버)
            │
            ├─ [저위험: 일반 단말] ➔ 방화벽 IP 차단 및 단말 네트워크 격리 100% 완전 자동 집행
            ▼
4. [고위험: 메인 DB 서버] ➔ 관제 팀장에게 Slack/Teams 모바일 승인 팝업 전송 ➔ 1-클릭 승인 수신
            │
            ▼
5. 방화벽 차단 API 및 EDR 격리 명령 멱등(Idempotent) 실행 ➔ 케이스 자동 종결 및 보고서 생성
```

**동작 원리**

1. **사건 접수**: Webhook을 통해 SIEM 상관 분석 이벤트 및 아티팩트 파싱
2. **자동 심층 조사**: 분석가 개입 없이 1초 내에 IP 평판, WHOIS, 내부 호스트 정보 병렬 수집
3. **위험 기반 분기**: 사전 정의된 위험 매트릭스에 따라 완전 자동 또는 승인 기반 모드 결정
4. **오케스트레이션 집행**: 다수의 보안 장비(방화벽, 스위치, AD, EDR)에 병렬로 REST API 페이로드 전송
5. **결과 검증 및 원복**: 조치 성공 여부를 폴링하여 실패 시 보상 트랜잭션을 통해 시스템 롤백 수행

#### 한줄 요약
- 인시던트 수신, TI 맥락 보강, 위험도 기반 승인 분기, 다중 API 멱등 실행, 사후 검증 및 롤백 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **완전 자동(Full-Auto) vs 승인 기반(HITL) vs 수동 개입(Manual)**: SOAR 플레이북의 인간 개입 수준에 따른 3단계 실행 모델.

</details>

| 비교 항목 | 완전 자동 대응 (Full-Auto) | 승인 기반 대응 (Human-in-the-Loop) | 수동 예외 대응 (Manual Interactive) |
|:---|:---|:---|:---|
| **인간 개입 여부** | **인간 개입 제로 (0% Human Touch)** | **사전 조사는 자동, 최종 조치만 승인** | 분석가가 SOAR 콘솔에서 수동 도구 실행 |
| **대응 소요 시간** | **수초 이내 ($\le 5\text{s}$ 극초저지연)** | 수 분 이내 (승인 대기 시간 의존) | 수십 분 ~ 수 시간 소요 |
| **주요 적용 대상** | 악성 피싱 메일 전사 삭제, 스캔 IP 차단 | **임원진 계정 잠금, 주요 서버 네트워크 격리**| 신종 제로데이 APT, 미정형 내부자 위협 |
| **비즈니스 리스크** | 오탐 시 정상 업무 트래픽 차단 위험 | **안전성 확보 (오탐 시 팀킬 방지)** | 휴먼 에러 및 대응 골든타임 유실 위험 |
| **운영 효율성** | **최고 수준 (관제 인력 리소스 보존)** | 우수 (위험과 효율의 최적 절충) | 낮음 (기존 수작업 관제와 유사) |

#### 한줄 요약
- 저위험 단순 반복 업무는 완전 자동, 고영향 크리티컬 조치는 HITL 승인, 비정형 침해는 수동 조사로 분기한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **API 레이트 리미트(Rate Limit) 및 타임아웃**: SOAR가 초당 수백 건의 차단 API를 방화벽으로 동시 호출할 때 대상 장비의 웹 관리 데몬이 과부하로 응답하지 못해 조치가 누락되는 장애.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고위험 조치(코어망 스위치 포트 셧다운)의 오탐 자동화로 인한 전사 서비스 중단 | 파급력 높은 조치에 대해 **HITL 승인 관문(Approval Gate) 강제 적용** | 비즈니스 가용성 훼손 원천 방지 및 안전한 자동화 달성 |
| 네트워크 단속 시 동일 플레이북 중복 재시도로 인한 방화벽 차단 룰 중복 누적 | 모든 조치 API 요청에 **멱등 키(Idempotency Token)** 부여 및 사전 상태 검증 | 중복 정책 생성 차단 및 방화벽/WAF 메모리 리소스 보존 |
| 다단계 조치 시나리오 중 특정 장비(EDR) API 실패로 인한 시스템 불일치 발생 | 플레이북 실패 핸들러에 **보상 트랜잭션(Compensation Workflow)** 정의 | 조치 전 상태로 안전한 원복(Rollback) 및 정합성 유지 |

#### 한줄 요약
- HITL로 비즈니스 중단을 막고, 멱등 키로 중복 룰을 방지하며, 보상 트랜잭션으로 상태 롤백을 보장한다.

## Ⅶ. 결론

- 복잡 다변화된 지능형 사이버 위협에 신속하고 일관되게 대응하기 위해 **SIEM과 연동된 SOAR 플랫폼 아키텍처**를 현대 SOC의 핵심 기반으로 구축하되, 안정적인 운영을 위해 **표준화된 플레이북 개발**, **HITL 승인 분기 체계**, **API 멱등성 및 보상 트랜잭션 메커니즘**을 결합하여 분석가 중심에서 오케스트레이션 중심의 자율 대응 보안관제를 완성

#### 한줄 요약
- SOAR 플랫폼과 플레이북 및 HITL 승인 통제를 결합하여 신속하고 안전한 보안 사고 자동 대응을 실현한다.
