## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SOAR (보안 오케스트레이션/자동화/대응)**: SIEM이 "해킹이다!" 하고 알람을 띄우면, 관제 요원이 일일이 방화벽 가서 IP 차단하고 백신 돌리는 수동 작업을 로봇처럼 자동화해 주는 지휘자(Orchestrator) 플랫폼이다.
- **플레이북 (Playbook)**: 사고 났을 때 우왕좌왕하지 않게 "1번: 로그 까보기, 2번: 위험도 판단, 3번: 방화벽 차단" 순서로 코딩해 놓은 자동화 대응 시나리오 대본이다.

</details>

- 정의: **SOAR** 기반 이종 보안 도구들을 하나로 연결하고, 탐지된 위협에 대한 반복적인 대응(조사/판단/조치)을 플레이북 기반으로 자동화 및 승인 실행하는 차세대 보안 플랫폼이다.
- 배경: 관제 센터(SIEM)가 하루에 수만 개씩 띄우는 알람을 분석가가 다 수동으로 창 띄워서 처리하려니까, **시간 지연(Delay)이 생기고 필수 차단 절차를 빼먹는 휴먼 에러가 속출해서 다 털렸다.**

#### 한줄 요약

- 알람 떴을 때 사람이 이리저리 뛰지 않고, 대본(플레이북)대로 로봇이 즉각 조사하고 차단 버튼까지 알아서 눌러주는 플랫폼이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **오케스트레이션 (Orchestration)**: 방화벽(팔로알토), 백신(크라우드스트라이크), 메일(익스체인지) 등 제조사가 다 달라서 말이 안 통하는 장비들을 API로 묶어서 한 번에 지휘하는 마에스트로 스킬이다.
- **실행 수준 분기**: 자동화가 편하다고 사장님 PC까지 무지성으로 차단하면 안 되니까, 쩌리 공격은 자동 컷트하고 위험한 조치는 사람 승인을 받게 나누는 똑똑한 기능이다.

</details>

- **지휘 (오케스트레이션)**: 서로 다른 이종 보안 장비의 API를 하나로 엮어서 조사와 차단 조치를 물 흐르듯 하나의 흐름으로 묶어낸다.
- **로봇 프로세스 (플레이북 자동화)**: 사람이 치던 지루한 반복 대응 절차를 정의된 플레이북을 통해 일관되고 매우 신속하게 실행한다.
- **정보 보강 (Enrichment)**: 경보가 뜨면 "이 IP는 북한 해커 IP고 타겟은 메인 DB다"라고 뼈와 살(자산/위협 정보)을 자동으로 갖다 붙여서 분석가한테 떠먹여 준다.

#### 한줄 요약

- 수십 개 벤더사 장비를 한 손으로 조종하고, 정해진 대본대로 체크와 조치를 매우 신속하게 자동화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **연동 어댑터 (Adapter)**: 장비마다 다 다른 API 규격과 명령어 사투리를 SOAR가 알아듣는 공통 언어로 번역해 주는 만능 통역기다.
- **승인/권한 관문**: 치명적인 사고를 치지 않게 핵심 서버 차단 같은 고위험 조치는 반드시 팀장 결재(승인)를 받아내게 만드는 브레이크다.

</details>

```text
[ SOAR 자동 대응 및 플레이북 직관적 비교 구조 ]

[ 1. 보안 경보 / 사건 맥락 입력부 ] ── (SIEM 알람 수신 + 위협 평판, 자산 중요도 보강)
      │
      ▼
[ 2. 플레이북 엔진 (두뇌) ] ── (시나리오 가동: 피싱 메일 대응 프로세스 시작!)
      │
      ▼
[ 3. 승인•권한 관문 ] ── (단순 찌끄레기 IP 차단은 자동 패스, 핵심망 격리는 팀장 승인 대기)
      │
      ▼ (결재 완료 시)
[ 4. 연동 어댑터 (통역기) ] ── (플레이북 명령을 각 보안 장비가 알아듣는 API 규격으로 번역)
      │
  ┌───┼───┐
  ▼   ▼   ▼
[방화벽] [백신] [메일] ── (5. 보안 통제 도구: IP 차단, PC 격리, 메일 삭제 동시 집행)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **사건 맥락 입력부** | SIEM 알람에 뼈와 살(위협 평판 등)을 붙여서 **조사할 세트를 만듦** | Context Input |
| **플레이북 엔진** | "A면 B해라"라고 짜인 **자동화 시나리오를 순서대로 돌리는 뇌** | Playbook Engine |
| **승인/권한 관문** | 사고 치지 않게 **크리티컬한 조치는 사람 결재 받아내는 브레이크** | Approval Gateway |
| **연동 어댑터** | 제조사마다 다른 장비 API를 **SOAR가 알아듣게 번역해 주는 통역기** | API Adapter |
| **보안 통제 도구** | SOAR의 지시를 받고 **실제로 IP를 자르거나 PC를 격리하는 행동대장** | Security Tools |

#### 한줄 요약

- 정보 수집 $\to$ 대본 실행 $\to$ 사람 승인 $\to$ 통역 거쳐서 $\to$ 장비들이 일제히 타격하는 5단계 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멱등 조치 (Idempotency)**: "IP 차단해"라는 명령이 네트워크 렉 걸려서 3번 쏴지더라도, 방화벽에 똑같은 룰이 3개 생기지 않고 딱 1번만 깔끔하게 적용되게 만드는 상태 유지 기술이다.
- **원복 (Rollback)**: 자동 조치로 방화벽을 막았는데 알고 보니 오탐(정상 트래픽)이었을 때, 버튼 하나로 차단 전 상태로 되돌려서 사고를 수습하는 기능이다.

</details>

```text
[ SOAR 플레이북 기반 자동 대응 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [사건 맥락 조회 및 보강]
│ (SOAR: SIEM 알람 들어옴. 이 IP 평판 조회해 봐. 악성이네!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [조치 영향도 및 가역성 판정]
│ (이거 단순 IP 차단임? 아니면 메인 DB 서버 셧다운임?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [실행 승인 요청 (분기)]   │
│ (고위험 조치는 관제 요원한테 팝업 띄워서 승인받음, 저위험은 자동 패스)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [멱등 조치 요청 및 실행]  │
│ (어댑터 통해 방화벽에 API 쏴서 즉각 원천 차단 때림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [상태 확인 및 원복 (Rollback) 판정]
│ (조치 실패하거나 알고 보니 오탐이면, 차단 풀고 롤백해서 수습함)
└──────────────────────────────┘
```

### 동작 원리

1. 사건 맥락 조회: SIEM 경보에 자산/신원/위협 평판(TI)을 결합해 분석가가 보기 좋게 세팅함.
2. 실행 승인 분기: 이거 차단했을 때 회사 망할 수도 있는 건지(영향도/가역성) 따져서 사람 승인 태움.
3. 멱등 조치 요청: 중복 룰 안 생기게 멱등 키(Idempotency Key) 꽂아서 방화벽이나 백신에 조치 쏨.
4. 조치 상태 판정: 내가 쏜 명령대로 방화벽 룰이 진짜 들어갔는지 응답(타임아웃) 체크함.
5. 원복 요청: 명령이 씹히거나 오탐 사고 친 거면 보상 단계 돌려서 조치 전 상태로 되돌림.

#### 한줄 요약

- 정보 긁고 $\to$ 위험한 건 승인받고 $\to$ 중복 안 되게 차단 때리고 $\to$ 사고 치면 롤백하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **완전 자동 / 승인 기반 / 수동 예외 대응**: SOAR가 얼마나 알아서 다 해줄 것인지 개입 수준을 나누는 기준이다.

</details>

| SOAR 실행 방식 비교 | **완전 자동 대응 (Full Auto)** | **승인 기반 대응 (Approval)** | **수동 예외 대응 (Manual)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | **로봇 청소기가 알아서 매일 청소함** | **로봇이 쓰레기 찾으면 주인이 버리라고 허락함** | **주인이 직접 빗자루 들고 구석구석 팖** |
| 적용 타겟 | 단순 스캔 공격 IP 차단, 뻔한 피싱 메일 삭제 | 임원진 계정 잠금, 메인 서버 네트워크 강제 격리 | 정해진 대본이 없는 신종 APT 공격, 복잡한 내부자 유출 |
| 핵심 작동 원리 | 플레이북 조건 맞으면 **사람 개입 1도 없이 0.1초 만에 즉시 컷트** | 귀찮은 조사는 SOAR가 다 해주고, **마지막 타격(차단) 승인 버튼만 사람이 누름** | 분석가가 SOAR 플랫폼을 수동 조작해서 직접 로그 까보고 대응함 |
| 최고 장점 | 관제 요원 갈아 넣지 않아도 **초고속 철저한 방어 및 피로도 0% 달성** | 치명적인 실수(사내망 셧다운 등)를 막는 **최후의 안전장치 확보** | 정해진 플레이북 룰이 없는 **변칙적인 공격에 유연하게 대응 가능** |
| 치명적 한계 | 오탐 났는데 무지성 차단해버리면 **정상 업무도 같이 터져버림** | 새벽에 요원 자느라 승인 늦게 누르면 **대응 골든타임 다 날아감** | 결국 사람 손을 타게 돼서 **SOAR 도입한 의미(자동화)가 퇴색됨** |

#### 한줄 요약

- 뻔하고 안전한 건 '완전 자동', 크리티컬한 건 '승인 대기', 듣도 보도 못한 신종 해킹은 '수동'으로 깐다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **보상 단계 (Compensation)**: SOAR가 "1. 방화벽 차단 $\to$ 2. 백신 스캔 $\to$ 3. PC 격리" 순서로 명령을 쐈는데 3번에서 뻑나면, 앞서 했던 1, 2번 조치를 깔끔하게 취소(원복)해서 시스템 상태가 꼬이지 않게 수습하는 단계다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 오탐 났는데 SOAR가 **사내망 전체를 셧다운 시켜버림** | 가역성(되돌리기 쉬운가) 파악 안 하고 고위험 조치를 무지성 '완전 자동'으로 돌려버림 | 영향도 빡센 조치(메인망 격리 등)는 무조건 **'승인/권한 관문' 태워서 팀장 결재 받게 함** | 고영향 오탐으로 인한 대형 IT 서비스 중단(팀킬) 철저한 방어 |
| 방화벽 API 통신 꼬여서 **동일한 차단 룰이 100개씩 생김** | 네트워크 렉 걸렸을 때 SOAR가 재시도(Retry) 쏘면서 조치가 중복 적용됨 | 조치 API 쏠 때 **'멱등 키(Idempotency)' 박아서 날리고, 쏘기 전에 상태 먼저 확인함** | 중복 룰 생성 찌꺼기 방지 및 방화벽/백신 장비 부하 감소 |
| 플레이북 돌다 중간에 뻑나서 **시스템 상태가 엉망진창으로 꼬임** | 다단계 조치 시나리오 중 하나만 실패했을 때 롤백(Rollback)하는 프로세스가 없음 | 에러/타임아웃 발생 시 **'보상 단계(Compensation)' 룰 가동해서 조치 전 상태로 원상복구함** | 부분 실패로 인한 상태 꼬임 방지 및 시스템 격리 유지 |

#### 한줄 요약

- 돌이킬 수 없는 조치는 팀장 결재받고, 렉 걸려도 중복 클릭 안 되게 만들고, 에러 나면 즉시 뒤로 가기(롤백) 해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 수동 관제의 극심한 피로도와 누락을 해결하기 위해, **SIEM 상관분석** 및 연동하여 **플레이북 자동화**, **승인 관문 통제**, **멱등 및 원복 조치** 활용 결합한 차세대 SOAR 대응 기조 확립함

#### 한줄 요약

- SOAR는 사람을 자르고 100% 무인으로 돌리는 마법이 아니다. 지루한 반복 작업은 로봇(플레이북)한테 던지고, 사람은 판단과 승인만 내리는 사령탑 체계를 짓는 거다.
