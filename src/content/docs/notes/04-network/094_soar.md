## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SOAR**: 이종 보안 장비 API를 연계(Orchestration)하고 플레이북(Automation)으로 침해 사고 대응(Response)을 가속화하는 보안 플랫폼.
- **Playbook (플레이북)**: 악성 IP 차단, 감염 PC 격리 등 표준 침해 대응 절차(SOP)를 워크플로우 코드로 작성한 자동화 시나리오.

</details>

- 정의/개념: 이종 보안 장비의 API를 연계하고 **표준 대응 절차를 플레이북으로 자동 실행하여 침해사고 분석·차단 시간을 단축하는 차세대 보안 운영 플랫폼**
- 배경/필요성: 보안 전문 인력 부족 및 수작업 관제의 한계로 인한 **수십 분 이상의 사고 대응 지연(MTTR), 분석가 피로도 누적 및 휴먼 에러 발생**

#### 한줄 요약
- 이종 보안 도구 오케스트레이션, 플레이북 기반 워크플로우 자동화, 사고 대응 시간 극소화를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MTTR (Mean Time to Respond)**: 침해 사고 인시던트 발생 후 격리 및 차단 등 실질적인 대응 조치가 완료될 때까지 걸리는 평균 시간.
- **Human-in-the-Loop (HITL)**: 완전 자동화 시 발생할 수 있는 오차단(핵심 DB 차단 등)을 막기 위해 고위험 조치 시 관리자의 승인 결재를 거치게 하는 제어 기제.

</details>

- **이종 보안 도구 API 오케스트레이션**: 방화벽, EDR, SIEM, 위협 인텔리전스(TI)를 **표준 REST API 커넥터로 단일 연동**
- **플레이북(Playbook) 기반 워크플로우 자동화**: 악성 IP 조회부터 격리까지의 **전 과정을 시나리오 코드로 자동 집행**
- **승인 분기(Human-in-the-Loop)를 통한 안정성 보장**: 미션 크리티컬 자산 제어 시 **관리자 1-클릭 승인 관문 강제로 오차단 방지**

#### 한줄 요약
- API 오케스트레이션, 플레이북 기반 자동화, HITL 승인 분기를 통한 가용성 보장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Orchestrator Engine**: BPMN 기반 워크플로우를 파싱하여 조건 분기, 반복문, API 호출을 관리하고 트랜잭션 정합성을 유지하는 핵심 엔진.

</details>

```text
[SOAR 보안 운영 자동화 및 오케스트레이션 파이프라인]
|-- Ingress Events (SIEM 상관 분석 알람, EDR 위협 티켓, Phishing Mail 신고)
`-- SOAR Platform Core Engine
    |-- 1. Threat Context Enricher (외부 VirusTotal TI 조회 & CMDB 자산 매핑)
    |-- 2. Playbook Orchestrator Engine (BPMN / Python 기반 대응 시나리오 실행)
    |-- 3. Human-in-the-Loop Approval Gate (고위험 조치 시 Slack/Teams 모바일 승인)
    `-- 4. Case Management & Audit Log (인시던트 티켓 수명주기 및 증적 감사 기록)
`-- Security Tools Integration (REST API 커넥터 기반 액션 실행)
    |-- Firewall / WAF Connector (악성 IP/도메인 차단 룰 자동 주입)
    |-- EDR Agent Connector (감염 엔드포인트 프로세스 Kill 및 네트워크 격리)
    `-- Email Gateway Connector (전사 수신함 피싱 메일 일괄 자동 삭제)
```

선의 의미: SIEM 경보가 인입되면 SOAR가 위협 정보를 보강하고 플레이북에 따라 관리자 승인을 거쳐 각 보안 장비 API로 일괄 차단 조치를 집행하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **위협 맥락 보강기** | 인입된 IP, 도메인, 파일 해시를 **TI 서비스와 CMDB에서 자동 조회·주입** | Enrichment |
| **플레이북 엔진** | 조건문, 루프, API 호출, 승인 분기를 포함한 **사고 대응 워크플로우 실행** | BPMN / Python |
| **승인/권한 관문** | 핵심 서버 격리 등 **비즈니스 중단 위험 조치에 대해 관리자 결재 강제** | HITL Gateway |
| **연동 어댑터 (App)** | 이종 보안 벤더별 **REST API 명세를 표준화하여 읽기/쓰기 액션 실행** | Plugin Hub |
| **케이스 관리 시스템**| 인시던트 티켓 생성, **증적 수집, 대응 이력 감사 로깅 및 보고서 생성** | Case Lifecycle |

#### 한줄 요약
- 맥락 보강기, 플레이북 엔진, HITL 승인 관문, 연동 어댑터, 케이스 관리 모듈이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Compensation Action (보상 트랜잭션)**: 다단계 자동 조치 수행 중 특정 단계 실패 시 앞서 실행된 차단 조치를 이전 정상 상태로 안전하게 롤백(Rollback)하는 복구 로직.

</details>

```text
SOAR 인시던트 접수, 맥락 보강, HITL 승인 및 API 집행 파이프라인
        │
   1. [인시던트 접수] SIEM에서 고위험 'C&C 통신 의심' 알람이 Webhook을 통해 SOAR로 전달
        │
   2. [자동 심층 조사] VirusTotal TI 평판 및 CMDB 자산 중요도를 1초 내에 자동 결합
        │
   3. [위험도 평가 및 분기] 사전 정의된 위험 매트릭스에 따라 일반 단말 vs 핵심 서버 판정
        │
   ├─ [저위험 일반 PC] ➔ 방화벽 IP 차단 및 단말 네트워크 격리 100% 완전 자동 집행
   ▼
4. [고위험 핵심 서버] ➔ 관제 팀장에게 모바일 1-클릭 승인 팝업 전송 후 승인 수신
        │
   ▼
5. [API 멱등 집행 및 롤백] 방화벽/EDR 차단 API를 멱등 실행하고 실패 시 보상 트랜잭션 롤백
```

#### 한줄 요약
- 인시던트 수신 → TI 맥락 보강 → 위험도 기반 승인 분기 → 다중 API 멱등 실행 → 사후 검증 및 롤백 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Full-Auto (완전 자동)** vs **HITL (승인 기반)** vs **Manual (수동 개입)**.

</details>

| 비교 항목 | 완전 자동 대응 (Full-Auto) | 승인 기반 대응 (Human-in-the-Loop) | 수동 예외 대응 (Manual Interactive) |
|:---|:---|:---|:---|
| **인간 개입 수준** | **인간 개입 제로 (0% Human Touch)** | **사전 조사는 자동, 최종 조치만 승인** | 분석가가 SOAR 콘솔에서 수동 도구 실행 |
| **대응 소요 시간** | **수 초 이내 ($\le 5\text{s}$ 극초저지연)** | 수 분 이내 (승인 대기 시간 의존) | 수십 분 ~ 수 시간 소요 |
| **주요 적용 대상** | **악성 피싱 메일 전사 삭제, 스캔 IP 차단**| **임원진 계정 잠금, 주요 서버 네트워크 격리**| 신종 제로데이 APT, 미정형 내부자 위협 |
| **비즈니스 리스크** | 오탐 시 정상 업무 트래픽 차단 위험 | **안전성 확보 (오탐으로 인한 서비스 다운 방지)**| 휴먼 에러 및 대응 골든타임 유실 위험 |
| **운영 효율성** | **최고 수준 (관제 인력 리소스 보존)** | 우수 (위험과 효율의 최적 절충) | 낮음 (기존 수작업 관제와 유사) |

#### 한줄 요약
- 저위험 단순 반복 업무는 완전 자동, 고영향 크리티컬 조치는 HITL 승인, 비정형 침해는 수동 조사로 분기한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Idempotency Token (멱등 키)**: 네트워크 단속 시 동일 플레이북이 재시도되더라도 대상 방화벽에 동일한 차단 룰이 중복 생성되지 않도록 보장하는 고유 토큰.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고위험 조치(코어망 스위치 포트 차단) 오탐 시 전사 비즈니스 서비스 중단 | 파급력 높은 조치에 대해 **`HITL 승인 관문(Approval Gate)` 강제 적용** | 비즈니스 가용성 훼손 방지 및 안전한 자동화 달성 |
| 네트워크 재시도로 인한 대상 방화벽의 동일 차단 룰 중복 누적 | 모든 조치 API 요청에 **`멱등 키(Idempotency Token)` 부여 및 상태 검증** | 중복 정책 생성 차단 및 방화벽 메모리 자원 보존 |
| 다단계 조치 시나리오 중 특정 장비 API 실패로 인한 시스템 불일치 | 플레이북 실패 핸들러에 **`보상 트랜잭션(Compensation Workflow)` 정의** | 조치 전 상태로 안전한 원복(Rollback) 및 정합성 유지 |
| 보안 장비 REST API 호출 쿼터 초과(Rate Limit)로 인한 조치 누락 | **비동기 큐잉 및 지수 백오프(Exponential Backoff) 재시도** | API 호출 폭주 제어 및 조치 누락 방지 |

#### 한줄 요약
- HITL로 비즈니스 중단을 막고, 멱등 키로 중복 룰을 방지하며, 보상 트랜잭션으로 상태 롤백을 보장한다.

## Ⅶ. 결론

- 복잡 다변화된 지능형 사이버 위협에 신속하고 일관되게 대응하기 위해 **SIEM과 연동된 SOAR 플랫폼 아키텍처를 현대 SOC의 핵심 기반으로 구축**하되, 안정적인 운영을 위해 **표준화된 플레이북 개발, HITL 승인 분기 체계, API 멱등성 및 보상 트랜잭션 메커니즘**을 결합하여 분석가 중심에서 오케스트레이션 중심의 자율 대응 보안관제 완성

#### 한줄 요약
- SOAR 플랫폼과 플레이북 및 HITL 승인 통제를 결합하여 신속하고 안전한 보안 사고 자동 대응을 실현한다.
