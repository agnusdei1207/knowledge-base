## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 오케스트레이션/자동화/대응(SOAR, Security Orchestration, Automation, and Response)**: 이종 보안 도구 연결 및 반복 사건 대응을 플레이북 기반으로 자동/승인 실행하는 보안 플랫폼.
- **보안 정보/이벤트 관리(SIEM, Security Information and Event Management)**: 다기종 로그 상관분석을 통해 보안 경보를 생성/통합하는 관제 플랫폼.
- **SOAR 플레이북 기반 보안 대응 자동화(SOAR Playbook-based Automation)**: 탐지 경보의 조사/판단/조치를 실행 가능한 절차로 연결하는 대응 자동화 방식.
- **지연/절차 누락(Delay & Process Omission)**: 분석가가 다종 보안 도구를 수동 전환하며 대응 시 발생되는 지연 및 필수 절차 누락 문제.

</details>

- 정의/개념: **SIEM** 경보를 수신하여 조사/조치를 연결하는 **SOAR 플레이북 기반 보안 대응 자동화(SOAR Playbook-based Automation)** 플랫폼.
- 배경/필요성: 수동 대응 시 발생되는 **지연/절차 누락(Delay & Process Omission)** 해소.

#### 한줄 요약

- 경보가 오면 여러 보안 도구를 사람이 옮겨 다니지 않고 정해진 순서로 조사하고 필요한 조치를 실행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **오케스트레이션(Orchestration)**: 서로 다른 보안 도구의 조회/판단/조치 호출을 단일 사건 흐름으로 연결하는 기능.
- **플레이북(Playbook)**: 사건 조건, 정보 수집, 분기, 승인, 조치와 원복 순서를 실행 가능한 절차로 정의한 표준 문서.
- **정보 보강(Enrichment)**: 경보에 자산 중요도, 사용자 정보, 위협 평판 및 과거 사건 이력을 자동 결합하는 처리 과정.
- **플레이북 자동화(Playbook Automation)**: 플레이북의 조회/분기/승인/조치 단계를 일관되게 실행하는 엔진 기능.
- **실행 수준 분기(Execution Branching)**: 탐지 신뢰도/조치 영향/가역성에 따라 자동/승인/수동 실행 모드를 구분하는 기능.

</details>

- **오케스트레이션**: 이종 보안 도구의 조사•조치를 연결한다.
- **플레이북 자동화**: **플레이북**에 정의한 반복 대응 절차를 일관되게 실행한다.
- **실행 수준 분기**: 영향도별 자동•승인•수동을 구분한다.
- **정보 보강**: 경보에 자산•신원•위협 정보를 추가한다.

#### 한줄 요약

- 안전한 조회는 자동화하고 계정 잠금처럼 영향이 큰 조치는 사람이 승인하도록 나눠야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사건 맥락 입력부**: 중복 경보를 묶고 자산•신원•위협 정보를 보강하는 구성요소이다.
- **플레이북 엔진**: 조건•분기•승인•조치 순서에 따라 플레이북을 실행하는 구성요소이다.
- **승인•권한 관문**: 조치 영향도별 승인과 최소 권한을 적용하는 통제 지점이다.
- **연동 어댑터**: 제품별 API 호출 형식과 오류를 공통 플레이북 인터페이스로 변환하는 구성요소이다.
- **보안 통제 도구**: 메일•단말•계정•네트워크에 대응 조치를 수행하는 제품이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 플레이북이 제품별 조회•조치 기능을 구조화해 호출하는 규약이다.

</details>

```text
사건 맥락 입력부
└─ 플레이북 엔진
   └─ 승인•권한 관문
      └─ 연동 어댑터
         └─ 보안 통제 도구
```

선의 의미: 사건 맥락과 플레이북 엔진 아래에 승인•권한 관문이 놓이고, 연동 어댑터가 최소 권한 범위에서 보안 통제 도구를 연결하는 정적 SOAR 플랫폼 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 사건 맥락 입력부(Context Input) | 경보 중복 제거, 자산/신원/위협 정보 보강 |
| 플레이북 엔진(Engine) | 조건/분기/승인/조치 순서에 따른 플레이북 실행 |
| 승인/권한 관문(Gateway) | 조치 영향도별 승인 및 최소 권한(Least Privilege) 적용 |
| 연동 어댑터(Adapter) | 제품별 API 호출/오류를 공통 인터페이스로 변환 |
| 보안 통제 도구(Control Tools) | 메일/단말/계정/네트워크 대응 조치 수행 |

#### 한줄 요약

- 경보에 필요한 정보를 붙이면 플레이북이 승인 조건을 확인하고 어댑터로 각 보안 도구의 조치를 호출한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멱등성(Idempotency)**: 같은 조치를 여러 번 호출해도 결과가 한 번 실행한 것과 같게 유지되는 성질이다.
- **원복(Rollback)**: 자동 조치가 잘못됐을 때 차단•격리•계정 상태를 조치 전으로 되돌리는 기능이다.
- **보상 단계**: 일부 조치 실패 시 앞서 수행한 변경을 상쇄하는 절차이다.
- **타임아웃**: 정해진 시간 내 응답이 없으면 호출 실패로 판정하는 제한이다.
- **사건 맥락 조회**: 자산 중요도•신원•위협 평판을 조회해 경보의 대응 맥락을 구성하는 단계이다.
- **실행 승인 요청**: 조치 신뢰도•영향•가역성을 근거로 담당자 승인을 요청하는 단계이다.
- **멱등 조치 요청**: 재시도해도 중복 효과가 발생하지 않도록 식별자를 포함해 조치를 호출하는 단계이다.
- **조치 상태•타임아웃 판정**: 의도 상태와 실제 결과를 대조하고 응답 기한 초과를 실패로 결정하는 단계이다.
- **원복 요청**: 실패나 오탐 때 보상 단계를 실행해 조치 전 상태로 복구하는 단계이다.

</details>

```text
보안 경보
      │
      ▼
1. 사건 맥락 조회
      │
      ▼
조치 영향도•가역성 판정
      ├─ 고위험: 2. 실행 승인 요청
      │              ├─ 거부: 사건 수동 이관
      │              └─ 승인
      └─ 저위험 자동
              │
              ▼
3. 멱등 조치 요청
              │
              ▼
4. 조치 상태•타임아웃 판정
              ├─ 성공: 사건 처리 결과 반환
              └─ 실패•오탐: 5. 원복 요청
```

### 동작 원리

1. **사건 맥락 조회**: 자산•신원•위협 평판을 결합
2. **실행 승인 요청**: 신뢰도•영향•가역성으로 승인 분기
3. **멱등 조치 요청**: 멱등 키와 최소 권한으로 조치 호출
4. **조치 상태•타임아웃 판정**: 의도 상태와 실제 결과 대조
5. **원복 요청**: 실패•오탐 시 보상 단계로 이전 상태 복구

#### 한줄 요약

- 경보를 정리하고 위험을 판단해 큰 조치는 승인받은 뒤 실행하며 도구가 실제로 바뀌었는지 확인하고 실패하면 되돌린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **완전 자동 대응**: 고신뢰•저영향•가역적 조치를 사람 승인 없이 즉시 실행하는 방식이다.
- **승인 기반 대응**: 자동 조사 후 영향이 큰 표준 조치를 사람 승인으로 실행하는 방식이다.
- **수동 예외 대응**: 신규•모호한 복합 사건을 분석가가 직접 조사하고 조치하는 방식이다.

</details>

| SOAR 실행 방식 | **완전 자동 대응** | **승인 기반 대응** | **수동 예외 대응** |
|:---|:---|:---|:---|
| 적용 기준 | 반복•가역적 고신뢰 조치 | 영향 큰 표준 조치 | 신규•모호한 복합 사건 |
| 핵심 특징 | 조건 충족 시 즉시 자동 조치 | 자동 조사 후 사람 승인 | 분석가의 직접 조사•조치 |
| 한계 | 오탐의 조치 확산 | 승인 대기의 대응 지연 | 수동 편차•단계 누락 |

> 요약: 탐지 신뢰도(Confidence), 조치 영향도(Impact), 가역성(Reversibility) 기반의 대응 자동화 방식 결정.

#### 한줄 요약

- 쉽게 되돌릴 반복 조치는 자동, 영향이 큰 조치는 승인, 처음 보는 복잡한 사건은 사람이 직접 처리한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가역성**: 실행한 보안 조치를 이전 상태로 되돌릴 수 있는 정도이다.
- **멱등 키(Idempotency Key)**: 재시도에서도 중복 조치를 막는 요청 식별자이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 오탐 조치의 업무 중단 | **가역성(Reversibility)**과 영향도별 **승인/권한 관문** 적용 | 저위험 자동 대응 및 고영향 오탐 차단 |
| API 재시도의 중복 차단 | **멱등 키(Idempotency Key)** 적용 및 실행 전 상태 확인 | 중복 조치 방지 및 시스템 부하 감소 |
| 제품 오류의 플레이북 중단 | **보상 단계(Compensation)**/타임아웃/원복 설계 | 부분 실패 시의 영향 격리 |

#### 한줄 요약

- SOAR가 피싱 메일과 악성 주소를 자동 차단하고 업무 중단 영향이 큰 계정 잠금은 담당자 승인 후 실행한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SOAR 실행 방식 선택**: 탐지 신뢰도•조치 영향•가역성에 따라 자동•승인•수동 대응을 결정하는 판단이다.

</details>

- 고신뢰•가역 조치는 **자동**, 고영향은 **승인**, 신규 사건은 **수동** 선택.

#### 한줄 요약

- SOAR는 사람을 없애는 도구가 아니라 반복 작업을 맡기고 위험한 판단은 승인과 원복 장치로 통제하는 플랫폼이다.
