## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **5GC(5G Core)**: 4G까지 쓰던 무식한 하드웨어 박스 장비들을 다 버리고, 코어망을 완전 100% 소프트웨어 클라우드로 바꿔버린 5G 전용 뇌(두뇌)다.
- **SBA(Service-Based Architecture)**: 코어망 기능들을 레고 블록(NF)처럼 쪼개서, 필요할 때마다 웹 API(RESTful)로 불러다 쓰는 5GC의 핵심 아키텍처 뼈대다.

</details>

- 정의: 5G 코어망의 제어 평면 기능(NF)들을 **웹 표준 RESTful API 기반으로 잘게 쪼개(모듈화)** 놓고, NRF를 통해 서로 동적으로 찾아서 호출하는 **클라우드 네이티브 아키텍처**
- 배경: 기존 4G 코어는 기능끼리 딱딱하게 하드코딩(P2P)되어 있어서, 새로운 기능(슬라이싱 등)을 끼워 넣거나 망을 늘릴 때마다 **망 전체를 뜯어고쳐야 하는 노가다를 해결하기 위해 등장함**

#### 한줄 요약

- 통신 장비 쇳덩이들을 버리고, 코어망 전체를 IT 웹 서버(API)처럼 가볍고 유연한 레고 블록으로 바꿔버린 혁명이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NF(Network Function)**: 4G 땐 커다란 박스 장비였는데, 5G에선 가상 머신(VM)이나 컨테이너에서 돌아가는 작은 소프트웨어 레고 블록(모듈)이다.
- **NRF(Network Repository Function)**: 코어망의 전화번호부다. 새로운 블록(NF)이 태어나면 여기 등록하고, 남이 필요하면 NRF한테 물어봐서 찾아간다.
- **CUPS**: 복잡한 머리 쓰는 일(제어, Control)과 단순 무식하게 데이터 나르는 일(사용자, User)을 싹둑 잘라서 분리하는 5G의 뼈대 기술이다.

</details>

- **RESTful API (웹 표준 통신)**: 옛날 통신사만의 개복잡한 통신 규약 안 쓰고, IT 개발자가 다 아는 웹 표준(HTTP/2, JSON)으로 NF들끼리 데이터를 주고받음.
- **NRF 중심의 자동 발견(Discovery)**: "나 새로 태어났어!" 하고 NRF에 등록하면, 딴 놈들이 NRF를 뒤져서 자동으로 찾아내 연결(Plug & Play)함.
- **CUPS 완벽 분리**: 머리(SMF)와 몸통(UPF)을 분리해 놔서, 트래픽 폭주하면 생각할 필요 없이 몸통(UPF)만 기지국 옆(MEC)으로 무한 복제해 던져놓을 수 있음.

#### 한줄 요약

- 통신 규약을 웹 표준(HTTP)으로 싹 바꾸고, 전화번호부(NRF) 만들어서 지들끼리 알아서 통신하게 만든 구조다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AMF(Access and Mobility Management Function)**: 폰이 기지국에 붙을 때 "너 누구냐, 요금 냈냐?" 검사하고, 차 타고 이동할 때 안 끊기게 챙겨주는 문지기다.
- **SMF(Session Management Function)**: "얘는 유튜브 보니까 데이터 팍팍 쏴라" 하고 데이터 길(세션)을 어떻게 뚫어줄지 작전 짜는 브레인(제어)이다.
- **UPF(User Plane Function)**: SMF가 시키는 대로 묵묵히 사용자 데이터를 인터넷으로 퍼다 나르는 택배 기사(사용자 평면)다.

</details>

```text
[ 5G 코어 SBA 직관적 비교 구조 ]

[ AMF (문지기) ]  [ SMF (브레인) ]  [ PCF (요금/정책) ]  [ UDM (DB) ]
       │              │                 │               │
───────┴──────────────┴────── (HTTP/2 웹 API 통신 버스) ┴──── [ NRF (전화번호부) ]
                              │
                   (PFCP: 길 뚫어라 명령)
                              │
                              ▼
                    [ UPF (택배 기사) ] ──▶ (외부 인터넷 넷플릭스)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **AMF** | 폰 접속하면 요금제 검사하고 **이동할 때 안 끊기게 챙겨주는 문지기** | 제어 (C) |
| **NRF** | 모든 NF들이 태어나면 여기다 번호 남기는 **코어망 전화번호부** | 제어 (C) |
| **SMF** | "얘는 무제한 요금제니까 길 팍팍 뚫어라" 하고 **작전 짜는 브레인** | 제어 (C) |
| **UPF** | 닥치고 인터넷으로 **데이터 짐만 빡세게 나르는 노가다 택배 기사** | 사용자 (U) |

#### 한줄 요약

- 머리 쓰는 놈들(AMF, SMF)은 API 버스로 떠들고, 무식하게 일하는 놈(UPF)은 밑에서 짐만 나른다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PFCP(Packet Forwarding Control Protocol)**: 뇌(SMF)가 손발(UPF)한테 "이 패킷은 이쪽 길로 쏴라" 하고 지시를 내리는 5G 표준 조종 프로토콜이다.

</details>

```text
[ SBA 기반 5G 데이터 길 뚫기 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [AMF 체크]           │
│ (폰이 인터넷 쓴다고 문 두드림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [NRF 전화번호부 조회]     │
│ (길 뚫어줄 SMF 누구 있냐?)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [SMF 작전 수립]           │
│ (ㅇㅋ 내가 길 뚫을게)        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [UPF 아바타 조종 (PFCP)]  │
│ (택배 기사야 이쪽으로 길 열어)
└──────────────┬───────────────┘
               ▼
     (폰이랑 인터넷 데이터 뚫림)
```

### 동작 원리

1. 접속 요청: 단말이 폰 켜면 AMF가 낚아채서 신원 검사함.
2. NRF 검색: AMF가 NRF한테 "지금 안 바쁜 SMF 번호 좀 줘" 하고 검색함.
3. 세션 제어: 번호 받은 AMF가 SMF를 찔러서 데이터 뚫을 작전을 짬.
4. 패킷 뚫기: SMF가 PFCP로 UPF(택배 기사)를 조종해서 실제 데이터 길(세션)을 뚫어버림.

#### 한줄 요약

- 문지기(AMF)가 전화번호부(NRF) 뒤져서 브레인(SMF) 부르면, 브레인이 택배 기사(UPF) 시켜서 길을 뚫는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

| 비교 항목 | **4G LTE 코어 (EPC)** | **5G 코어 (SBA)** |
|:---|:---|:---|
| 직관적 비교 구조 | 거대한 쇳덩이 장비끼리 **선으로 1:1 하드코딩 (P2P)** | 레고 블록(NF)들이 **웹 표준(API)으로 둥둥 떠다님** |
| 핵심 프로토콜 | 통신사만 아는 개복잡한 프로토콜 (GTP-C 등) | IT 개발자도 다 아는 **웹 표준 (HTTP/2, REST API)** |
| 기능 추가/확장 | 장비 뜯어서 펌웨어 올리고 **망 전체가 벌벌 떨어야 함** | 그냥 클라우드에 **소프트웨어(NF) 하나 더 띄우면 됨** |
| 머리/몸통 분리 | 머리랑 몸통이 **부분적으로 붙어 있어서 무거움** | 뇌(SMF)랑 손발(UPF)을 **완전 찢어발겨서 따로 놂 (CUPS)** |
| 슬라이싱 지원 | 불가능 (모두가 같은 길 씀) | 가상 차선으로 **완벽하게 찢어버림 (Network Slicing)** |

#### 한줄 요약

- 통신사 고인물 장비에서 벗어나, 넷플릭스나 구글처럼 유연한 IT 클라우드 아키텍처로 환골탈태한 게 5GC다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Circuit Breaker(서킷 브레이커)**: 어느 한 모듈(NF)이 뻗었을 때 다른 모듈까지 덩달아 뻗는 대참사(연쇄 장애)를 막기 위해, 고장 난 놈은 쳐다보지도 않고 전원을 뚝 끊어버리는 방어 기술이다.
- **mTLS**: 서로 웹 API로 통신하니까 해커가 중간에 장난칠 수 없도록, 양쪽 다 쌍방으로 인증서 까고 통신하는 빡센 암호화 방패다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| AMF 하나 뻗었는데 **코어망 전체가 연달아 다 뻗어버림** | 한 놈이 죽으면 호출 대기하다가 다 같이 죽는 연쇄 장애 | **Circuit Breaker(서킷 브레이커)** 넣어서 뻗은 놈은 쿨하게 손절 | 꼬리 자르기로 5G 코어망 전체 셧다운 컷 |
| 해커가 AMF인 척 **API 찔러서 코어망 다 털어버림** | 웹 표준(HTTP/2) 쓰다 보니 가짜 서버 띄워서 해킹하기 쉬움 | **mTLS 쌍방 인증** 및 OAuth 2.0 토큰으로 입장 빡세게 통제 | 불법 위장 접근 컷 및 패킷 100% 암호화 |
| 이미 뒈진 SMF한테 **계속 일감 던지다가 에러 뿜어댐** | 뻗은 놈이 NRF(전화번호부)에 지 이름 안 지우고 뻗어버림 | NRF가 초 단위로 **심박수(Heartbeat)** 체크해서 죽으면 지움 | 좀비 NF 호출하는 바보짓 사전 예방 |

#### 한줄 요약

- API로 대화하니까 해킹 방어(mTLS) 빡세게 하고, 죽은 놈은 서킷 브레이커로 칼같이 꼬리 잘라야 연쇄 대참사를 막는다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 하드웨어에 종속된 4G 코어를 버리고, 철저히 웹(HTTP/2)과 클라우드 네이티브로 진화한 **SBA**를 통해 **네트워크 슬라이싱**과 무한 스케일링을 달성하는 5GC 소프트웨어 아키텍처 기조 확립함

#### 한줄 요약

- 5G 코어(SBA)는 통신 기술이라기보단, 구글이나 넷플릭스가 트래픽을 처리하는 'IT 클라우드 기술'을 통신망에 그대로 복붙한 거다.
