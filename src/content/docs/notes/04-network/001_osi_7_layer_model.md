## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **개방형 시스템 간 상호접속 7계층 모델(Open Systems Interconnection 7-Layer Model, OSI 7-Layer Model)**: 통신 기능과 책임을 일곱 계층으로 나누어 이기종 시스템의 상호운용 기준을 제공하는 대표적 참조 모델.

</details>

- 정의/개념: 통신 기능과 책임을 분리한 **개방형 시스템 간 상호접속 7계층 모델(Open Systems Interconnection 7-Layer Model, OSI 7계층 모델)**.
- 배경/필요성: 공통 계층 기준 부재 시 이기종 장비 간 상호운용성 제약 발생.

#### 한줄 요약

- 이기종 시스템 간 상호운용성 보장 및 계층화 아키텍처 기반 장애 격리 기능을 제공한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **계층 인터페이스(Layer Interface)**: 인접한 두 계층이 서비스를 요청하고 처리 결과를 전달하는 상호작용 경계.
- **프로토콜 데이터 단위(Protocol Data Unit, PDU)**: 각 계층이 고유 제어 정보를 데이터에 부착하여 처리하는 단위.
- **캡슐화(Encapsulation)**: 송신 계층이 하위 계층으로 데이터를 전달하며 제어 정보를 부착하는 메커니즘.
- **역캡슐화(Decapsulation)**: 수신 계층이 상위 계층으로 데이터를 전달하며 제어 정보를 역순으로 제거하는 동작.

</details>

- **계층 인터페이스**를 통한 구현 변경 영향의 효과적 격리.
- **프로토콜 데이터 단위(Protocol Data Unit, PDU)** 기반 처리 책임 및 장애 범위 구분.
- **캡슐화(Encapsulation)** 및 **역캡슐화(Decapsulation)**를 활용한 제어 정보의 대칭적 처리.

#### 한줄 요약

- 계층 결합도 분리와 서비스 접근점(SAP) 정의를 통해 하위 계층 변경이 상위 계층에 미치는 파급 효과를 차단한다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **전송 제어 프로토콜(Transmission Control Protocol, TCP)**: 포트 번호로 애플리케이션을 식별하고 전송 순서 및 재전송을 제어하는 신뢰성 전송 프로토콜.
- **인터넷 프로토콜(Internet Protocol, IP)**: 출발지와 목적지 주소를 기반으로 패킷의 최적 전달 경로를 결정하는 네트워크 프로토콜.
- **매체 접근 제어(Media Access Control, MAC)**: 동일 데이터 링크 내 장치를 식별하고 프레임을 전송하는 물리적 계층 제어 기능.

</details>

```text
응용 계층
│
표현 계층
│
세션 계층
│
전송 계층
│
네트워크 계층
│
데이터링크 계층
│
물리 계층
```

선의 의미: 인접 계층 간 서비스 인터페이스로서 상위 데이터 의미와 하위 전달 책임을 분리 및 결합하는 관계 표시.

| 구성요소 | 책임 |
|:---|:---|
| 응용 계층 | 사용자 네트워크 서비스 제공 |
| 표현 계층 | 데이터 형식•암호화•압축 변환 |
| 세션 계층 | 통신 대화•동기화 상태 관리 |
| 전송 계층 | **전송 제어 프로토콜(Transmission Control Protocol, TCP)** 등 포트 기반 종단 전달 제어 |
| 네트워크 계층 | **인터넷 프로토콜(Internet Protocol, IP)** 주소 기반 경로 선택 |
| 데이터링크 계층 | **매체 접근 제어(Media Access Control, MAC)** 주소 기반 프레임 전달 |
| 물리 계층 | 비트를 전기•광•무선 신호로 전송 |

#### 한줄 요약

- 위층은 사용자 데이터의 의미를 다루고 아래층으로 갈수록 전달 경로와 신호를 다룬다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **세그먼트(Segment)**: 전송 계층에서 헤더가 부착된 데이터 단위.
- **패킷(Packet)**: 네트워크 계층에서 라우팅 정보가 포함된 데이터 단위.
- **프레임(Frame)**: 데이터링크 계층에서 물리적 주소와 에러 제어 정보가 포함된 데이터 단위.
- **비트(Bit)**: 물리 계층에서 신호로 전환되어 전송되는 최소 데이터 단위.

</details>

```text
송신 응용 데이터
      |
      v
1. 캡슐화
      |
      +-- 응용•표현•세션 ---- 데이터
      +-- 전송 계층 -------- 세그먼트
      +-- 네트워크 계층 ---- 패킷
      +-- 데이터링크 계층 -- 프레임
      `-- 물리 계층 -------- 비트
                                  |
                              전송 매체
                                  |
                                  v
                           2. 역캡슐화
                                  |
                                  +-- 비트
                                  +-- 프레임
                                  +-- 패킷
                                  +-- 세그먼트
                                  `-- 수신 응용 데이터
```

### 동작 원리

1. **캡슐화(Encapsulation)**: 계층별 제어 헤더 부착을 통한 **프로토콜 데이터 단위(Protocol Data Unit, PDU)** 생성.
2. **역캡슐화(Decapsulation)**: **비트(Bit)**부터 **세그먼트(Segment)** 순의 헤더 제거를 통한 원본 데이터 복원.

#### 한줄 요약

- 송신자는 계층별 주소표를 붙여 보내고 수신자는 아래층부터 주소표를 떼어 원본을 복원한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **전송 제어 프로토콜/인터넷 프로토콜(Transmission Control Protocol/Internet Protocol, TCP/IP Model)**: 실제 인터넷 표준으로 활용되는 4계층 프로토콜 스택 아키텍처.

</details>

| 계층 모델 | **개방형 시스템 간 상호접속 7계층 모델(Open Systems Interconnection 7-Layer Model, OSI 7계층 모델)** | **전송 제어 프로토콜/인터넷 프로토콜(Transmission Control Protocol/Internet Protocol, TCP/IP) 모델** |
|:---|:---|:---|
| 적용 기준 | 계층 책임•장애 분석 | 인터넷 통신 구현 |
| 핵심 특징 | 기능•책임을 7계층으로 분리 | 프로토콜을 4계층으로 통합 |
| 한계 | 프로토콜과 경계 불일치 | 세부 계층 책임 분석 제한 |

> 요약: 책임 분석 측면의 OSI 모델과 실무 구현 측면의 TCP/IP 모델 간 역할 분담.

#### 한줄 요약

- OSI는 통신 업무를 세밀히 나눈 설계도이고 TCP/IP는 인터넷에서 쓰는 묶음이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최대 전송 단위(Maximum Transmission Unit, MTU)**: 단일 데이터 링크에서 단편화 없이 전송 가능한 최대 IP 패킷 크기.
- **방화벽(Firewall)**: IP, 포트, 상태 정보를 기반으로 네트워크 트래픽을 필터링 및 통제하는 보안 솔루션.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 계층 간 증상이 혼재된 장애 | 물리 계층부터 **프로토콜 데이터 단위(Protocol Data Unit, PDU)** 상향 추적 | 장애 범위 축소 |
| 주소•포트•응용 필드가 혼재된 정책 | 통제 대상에 맞춰 **방화벽(Firewall)** 배치 | 정책 오탐•누락 감소 |
| 헤더 누적으로 MTU 초과 | **최대 전송 단위(Maximum Transmission Unit, MTU)** 산정 | 단편화•폐기 예방 |
| 프로토콜 경계와 모델 불일치 | TCP/IP 경계로 구현 재매핑 | 설계 해석 오류 감소 |

#### 한줄 요약

- 케이블부터 IP와 포트까지 계층 순서로 확인하면 장애 범위를 빠르게 좁힐 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **계층별 장애 분석(Layered Troubleshooting)**: 수집된 PDU 및 주소 유형을 기준으로 장애 발생 계층을 단계적으로 국소화하는 기법.
- **점검 시작점 결정(Starting Point Selection)**: 오류 현상 및 헤더 분석 결과에 따라 최초 진단 계층을 정하는 의사결정 과정.

</details>

- **계층별 장애 분석** 및 **점검 시작점 결정**을 통한 PDU 및 주소 유형 기준 계층별 순차적 점검 수행.

#### 한줄 요약

- 오류가 난 데이터 단위와 주소를 확인하면 어느 계층부터 점검할지 정할 수 있다.
