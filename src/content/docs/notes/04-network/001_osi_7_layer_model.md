## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **OSI 7-Layer Model (개방형 시스템 상호연결 7계층)**: ISO(국제표준화기구)가 이기종 시스템 간 통신 호환성을 위해 네트워크 기능을 7개 계층으로 표준화한 참조 아키텍처.
- **PDU (Protocol Data Unit)**: 각 계층에서 프로토콜 처리를 위해 헤더와 페이로드를 결합한 표준 전송 단위 (Data, Segment, Packet, Frame, Bit).

</details>

- 정의/개념: 이기종 시스템 간의 상호 운용성을 보장하기 위해 **통신 프로토콜 기능을 7단계로 모듈화한 ISO 국제 표준 네트워크 참조 모델**
- 배경/필요성: 초기 벤더사별 독점 프로토콜 난립으로 인한 **이기종 장비 간 상호 통신 불가, 네트워크 확장 제약 및 장애 격리 불가**

#### 한줄 요약
- 계층별 독립 모듈화와 표준 PDU 캡슐화를 통해 이기종 네트워크 통신과 장애 격리를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Encapsulation & Decapsulation (캡슐화 및 역캡슐화)**: 상위 계층 데이터에 제어 헤더를 덧붙여 하위로 전달(캡슐화)하고, 수신 측에서 하위 헤더를 벗겨내며 상위로 전달(역캡슐화)하는 과정.
- **Service Access Point (SAP)**: 인접 계층 간에 상호 서비스를 주고받기 위해 정의된 논리적 인터페이스 접점.

</details>

- 하위 계층 구현 변경이 상위 계층에 영향을 주지 않는 **계층별 독립성 및 모듈화**
- 송신 측 헤더 부착(캡슐화)과 수신 측 헤더 제거(역캡슐화)를 통한 **단계적 프로토콜 제어**
- 각 계층 간 명확한 인터페이스를 제공하는 **서비스 접근점(SAP) 기반 통신**

#### 한줄 요약
- 모듈화, 캡슐화/역캡슐화, 계층 간 표준 인터페이스를 통해 네트워크 복잡도를 분할 정복한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **OSI 7계층 계층별 PDU**: L7~L5(Data/Message), L4(Segment), L3(Packet/Datagram), L2(Frame), L1(Bit).

</details>

```text
[OSI 7-Layer Reference Model 아키텍처]
|-- Upper Layers (응용/데이터 생성 계층)
|   |-- L7. Application Layer (HTTP, DNS, SMTP: 사용자 프로세스 네트워크 인터페이스) -> Data
|   |-- L6. Presentation Layer (TLS, JPEG: 데이터 포맷 변환, 압축, 암복호화) -> Data
|   `-- L5. Session Layer (Socket, RPC: 응용 간 세션 수립, 대화 동기화) -> Data
`-- Lower Layers (전송 및 네트워크 하부 계층)
    |-- L4. Transport Layer (TCP, UDP: 종단 간 신뢰성 제어, 포트 다중화) -> Segment
    |-- L3. Network Layer (IP, ICMP, 라우터: 논리적 IP 주소 지정, 최적 경로 라우팅) -> Packet
    |-- L2. Data Link Layer (Ethernet, MAC, L2 스위치: 인접 노드 간 프레임 전송, 에러 제어) -> Frame
    `-- L1. Physical Layer (케이블, NIC, 리피터: 비트 스트림의 전기/광 신호 물리 전송) -> Bit
```

선의 의미: 계층 및 상위 계층의 데이터가 하위 계층으로 전달되며 헤더가 추가되고 하위 물리 계층을 통해 전송되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **L7 응용 계층 (Application)** | 사용자 애플리케이션에 **웹(HTTP), 전자우편(SMTP), 도메인 조회(DNS) 네트워크 인터페이스 제공** | 최상위 인터페이스 |
| **L6 표현 계층 (Presentation)**| 송수신자 간 구문 차이를 해결하기 위해 **데이터 암복호화(TLS), 압축, 표준 포맷 변환 수행** | 구문 및 표현 변환 |
| **L5 세션 계층 (Session)** | 응용 프로세스 간의 **논리적 통신 세션 수립, 유지, 동기화(Sync Point) 관리** | 전이중/반이중 제어 |
| **L4 전송 계층 (Transport)** | 포트(Port) 기반 **종단 간(End-to-End) 신뢰성 제어, 흐름 제어, 혼잡 제어 및 오류 복구** | TCP / UDP |
| **L3 네트워크 계층 (Network)** | IP 주소를 기반으로 **서로 다른 네트워크 간 최적 경로를 설정(Routing)하고 패킷 포워딩** | IP, 라우터 |
| **L2 데이터링크 계층 (Data Link)**| MAC 주소를 기반으로 **인접 노드(Node-to-Node) 간 프레임 전송, 흐름 제어, CRC 오류 검출** | Ethernet, L2 스위치 |
| **L1 물리 계층 (Physical)** | 상위 프레임을 **0과 1의 비트(Bit) 전기적/광학적 신호로 변환하여 물리 매체로 송출** | 케이블, 커넥터 |

#### 한줄 요약
- L7 응용부터 L1 물리 계층까지 각 계층이 독립된 PDU와 책임을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캡슐화 5단계**: 응용 데이터 생성 $\to$ L4 TCP 헤더 부착 $\to$ L3 IP 헤더 부착 $\to$ L2 Ethernet 헤더/트레일러 부착 $\to$ L1 비트 전송.

</details>

```text
송신 호스트 (데이터 캡슐화)                     수신 호스트 (데이터 역캡슐화)
┌──────────────────────────────┐              ┌──────────────────────────────┐
│ [L7~L5] Application Data 생성 │              │ [L7~L5] Application Data 수신 │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L4] TCP 헤더 부착 (Segment)  │              │ [L4] TCP 헤더 검증 및 제거    │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L3] IP 헤더 부착 (Packet)    │              │ [L3] IP 헤더 검증 및 라우팅   │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L2] MAC/FCS 부착 (Frame)    │              │ [L2] CRC 오류 검사 및 역캡슐화│
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L1] 물리 신호 변환 (Bit)    │ ───────────▶ │ [L1] 비트 신호 수신 및 프레임│
└──────────────────────────────┘ (물리 케이블)└──────────────────────────────┘
```

#### 한줄 요약
- 송신 측은 L7에서 L1으로 캡슐화하고 수신 측은 L1에서 L7으로 역캡슐화하여 데이터를 복원한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OSI 7계층 vs TCP/IP 4계층**: 개념적 표준 참조 모델(OSI 7계층)과 인터넷 상용 구현 표준 프로토콜 스택(TCP/IP 4계층).

</details>

| 비교 항목 | OSI 7계층 참조 모델 | TCP/IP 4계층 구현 모델 |
|:---|:---|:---|
| 핵심 성격 및 목적 | **이론적이고 학술적인 표준 네트워크 참조 모델** | **실제 인터넷에서 작동하는 실용적 프로토콜 스택** |
| 계층 수 및 구성 | **7개 계층 (L1~L7 세분화)** | **4개 계층 (응용, 전송, 인터넷, 네트워크 인터페이스)**|
| 상위 계층 매핑 | 응용(L7), 표현(L6), 세션(L5) 분리 | **응용 계층(Application)으로 단일 통합** |
| 하위 계층 매핑 | 데이터링크(L2), 물리(L1) 분리 | **네트워크 인터페이스(Network Access)로 통합** |
| 주요 실무 활용 | 네트워크 아키텍처 설계 및 **계층별 장애 진단 기준** | 웹(HTTP), DNS 등 실제 통신 소프트웨어 및 패킷 구현 |

#### 한줄 요약
- OSI는 계층별 책임과 장애 진단의 기준 모델이며, TCP/IP는 실제 인터넷의 상용 구현 스택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Bottom-Up Troubleshooting (상향식 장애 분석)**: L1 물리 계층(링크 불빛, 케이블)부터 L2(MAC), L3(IP Ping), L4(Port Telnet), L7(HTTP) 순으로 점검하는 체계적 진단 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 네트워크 장애 발생 시 원인 구간 파악 불가로 MTTR 지연 | **L1(물리링크)부터 L7(응용)까지 순차 점검하는 `상향식(Bottom-Up) 진단` 적용** | 장애 원인 국소화 및 복구 시간 단축 |
| 터널링(IPsec/GRE) 헤더 추가로 인한 패킷 크기 초과 및 단편화 | **경로 MTU 탐색(PMTUD) 및 `TCP MSS Clamping` 값 최적화** | 패킷 분할 오버헤드 및 드롭 방지 |
| L3/L4 방화벽 통과 후 L7 웹 애플리케이션 공격(SQLi, XSS) 노출 | **L7 페이로드를 심층 검사하는 `웹 방화벽(WAF) 및 차세대 방화벽(NGFW)` 구축** | 응용 계층 지능형 침해 원천 차단 |
| 스위치 루핑 발생으로 브로드캐스트 스톰 및 L2 네트워크 마비 | **스위치 포트에 `Spanning Tree Protocol (RSTP) 및 BPDU Guard` 필수 활성화** | L2 루프 자동 차단 및 가용성 보장 |

#### 한줄 요약
- 상향식 장애 진단, MSS 최적화, L7 방화벽 검사, RSTP 루프 방어로 운영한다.

## Ⅶ. 결론

- 네트워크 시스템의 표준화와 상호 운용성을 확보하기 위해 **ISO의 OSI 7계층 참조 모델을 아키텍처 및 장애 진단의 표준 프레임워크로 채택**하고, **실무에서는 TCP/IP 프로토콜 스택과 상향식(Bottom-Up) 트러블슈팅 및 계층별 보안 가드레일**을 결합하여 견고한 엔터프라이즈 네트워크 인프라 완성

#### 한줄 요약
- OSI 7계층 모델은 7단계 모듈화와 캡슐화를 통해 이기종 통신을 보장하고 네트워크 설계와 장애 진단의 표준을 제공하는 핵심 참조 모델이다.
