## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **OSI 7-Layer Model (개방형 시스템 상호연결 7계층)**: ISO(국제표준화기구)가 이기종 시스템 간 통신 호환성을 위해 네트워크 기능을 7개 계층으로 표준화한 참조 아키텍처.
- **PDU (Protocol Data Unit)**: 각 계층에서 프로토콜 처리를 위해 헤더와 페이로드를 결합한 표준 전송 단위 (Data, Segment, Packet, Frame, Bit).

</details>

- 정의/개념: 통신 기능을 7단계로 모듈화한 **OSI 참조 모델**
- 배경/필요성: 과거 벤더별 독점 네트워크 아키텍처(IBM SNA, DECnet 등) 난립으로 인한 이기종 시스템 간 상호 통신 불가, 장비 교체 시마다 발생하는 막대한 프로토콜 변환 개발 비용 및 장애 발생 시 원인 규명의 어려움을 해결하기 위해, ISO(국제표준화기구)가 네트워크 통신 전 과정을 7개 계층으로 분할하고 계층 간 인터페이스(SAP)와 PDU 캡슐화 규칙을 표준화한 OSI 7계층 참조 모델을 정립하여 **이기종 시스템 간 호환성 보장, 계층별 독립적 기술 진화 및 체계적인 상향식(Bottom-Up) 장애 격리**를 달성할 필요

#### 한줄 요약
- 계층별 독립 모듈화와 표준 PDU 캡슐화를 통해 이기종 네트워크 통신과 장애 격리를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Encapsulation & Decapsulation (캡슐화 및 역캡슐화)**: 상위 계층 데이터에 제어 헤더를 덧붙여 하위로 전달(캡슐화)하고, 수신 측에서 하위 헤더를 벗겨내며 상위로 전달(역캡슐화)하는 과정.
- **Service Access Point (SAP)**: 인접 계층 간에 상호 서비스를 주고받기 위해 정의된 논리적 인터페이스 접점.

</details>

- 하위 계층 구현 변경이 상위 계층에 영향을 주지 않는 **계층별 독립성 및 모듈화**
- 송신 측 헤더 부착(캡슐화)과 수신 측 헤더 제거(역캡슐화)를 통한 **단계적 프로토콜 제어**
- 각 계층 간 명확한 인터페이스를 제공하는 **서비스 접근점(SAP) 기반 통신**

#### 한줄 요약
- 모듈화, 캡슐화/역캡슐화, 계층 간 표준 인터페이스를 통해 네트워크 복잡도를 분할 정복한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **OSI 7계층 계층별 PDU**: L7~L5(Data/Message), L4(Segment), L3(Packet/Datagram), L2(Frame), L1(Bit).

</details>

```text
[OSI 7-Layer Reference Model 아키텍처]
|-- Upper Layers (응용/데이터 생성 계층)
|   |-- L7. Application: 사용자 인터페이스 | Data
|   |-- L6. Presentation: 변환·압축·암호화 | Data
|   `-- L5. Session: 세션·대화 동기화 | Data
`-- Lower Layers (전송 계층)
    |-- L4. Transport: 종단 신뢰성·포트 | Segment
    |-- L3. Network: IP 주소·라우팅 | Packet
    |-- L2. Data Link: 인접 전송·오류 검출 | Frame
    `-- L1. Physical: 전기·광 신호 전송 | Bit
```

선의 의미: 상위·하위 계층군과 각 계층의 정적 포함 관계

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **L7 응용 계층** | HTTP·SMTP·DNS **서비스 인터페이스** 제공 | 최상위 인터페이스 |
| **L6 표현 계층**| **암복호화·압축·포맷 변환** 수행 | 구문 및 표현 변환 |
| **L5 세션 계층** | 통신 **세션 수립·유지·동기화** 관리 | 전이중·반이중 제어 |
| **L4 전송 계층** | 포트 기반 **종단 신뢰성·흐름·혼잡 제어** | TCP·UDP |
| **L3 네트워크 계층** | IP 기반 **경로 설정·패킷 포워딩** | IP·라우터 |
| **L2 데이터링크 계층**| MAC 기반 **프레임 전송·CRC 오류 검출** | Ethernet·L2 스위치 |
| **L1 물리 계층** | 비트를 **전기·광 신호**로 변환해 송출 | 케이블·커넥터 |

#### 한줄 요약
- L7 응용부터 L1 물리 계층까지 각 계층이 독립된 PDU와 책임을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캡슐화 5단계**: 응용 데이터 생성 $\to$ L4 TCP 헤더 부착 $\to$ L3 IP 헤더 부착 $\to$ L2 Ethernet 헤더/트레일러 부착 $\to$ L1 비트 전송.

</details>

```text
송신 호스트 (데이터 캡슐화)                     수신 호스트 (데이터 역캡슐화)
┌──────────────────────────────┐              ┌──────────────────────────────┐
│ [L7~L5] Application Data 생성 │              │ [L7~L5] Application Data 수신 │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L4] TCP 헤더 부착 (Segment)  │              │ [L4] TCP 헤더 검증 및 제거    │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L3] IP 헤더 부착 (Packet)    │              │ [L3] IP 헤더 검증 및 라우팅   │
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L2] MAC/FCS 부착 (Frame)    │              │ [L2] CRC 오류 검사 및 역캡슐화│
└──────────────┬───────────────┘              └──────────────▲───────────────┘
               │                                             │
               ▼                                             │
┌──────────────────────────────┐              ┌──────────────┴───────────────┐
│ [L1] 물리 신호 변환 (Bit)    │ ───────────▶ │ [L1] 비트 신호 수신 및 프레임│
└──────────────────────────────┘ (물리 케이블)└──────────────────────────────┘
```

#### 한줄 요약
- 송신 측은 L7에서 L1으로 캡슐화하고 수신 측은 L1에서 L7으로 역캡슐화하여 데이터를 복원한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OSI 7계층 vs TCP/IP 4계층**: 개념적 표준 참조 모델(OSI 7계층)과 인터넷 상용 구현 표준 프로토콜 스택(TCP/IP 4계층).

</details>

| 모델 | OSI 7계층 참조 모델 | TCP/IP 4계층 구현 모델 |
|:---|:---|:---|
| 핵심 성격 | **표준 네트워크 참조 모델** | **인터넷 구현 프로토콜 스택** |
| 계층 구성 | **7개 계층**으로 세분화 | **4개 계층**으로 통합 |
| 상위 계층 매핑 | 응용(L7), 표현(L6), 세션(L5) 분리 | **응용 계층(Application)으로 단일 통합** |
| 하위 계층 매핑 | 데이터링크(L2), 물리(L1) 분리 | **네트워크 인터페이스(Network Access)로 통합** |
| 실무 활용 | 아키텍처 설계와 **계층별 장애 진단** | 인터넷 통신 소프트웨어 구현 |

#### 한줄 요약
- OSI는 계층별 책임과 장애 진단의 기준 모델이며, TCP/IP는 실제 인터넷의 상용 구현 스택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Bottom-Up Troubleshooting (상향식 장애 분석)**: L1 물리 계층(링크 불빛, 케이블)부터 L2(MAC), L3(IP Ping), L4(Port Telnet), L7(HTTP) 순으로 점검하는 체계적 진단 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장애 원인 구간 불명확으로 MTTR 증가 | L1부터 L7까지 **상향식 진단** | 원인 국소화와 복구 시간 단축 |
| 터널 헤더로 MTU 초과·단편화 | **PMTUD·MSS Clamping** 적용 | 패킷 분할과 드롭 방지 |
| 방화벽 통과 후 L7 공격 노출 | **WAF·NGFW**로 페이로드 검사 | 응용 계층 침해 차단 |
| 스위치 루프로 브로드캐스트 스톰 | **RSTP·BPDU Guard** 활성화 | L2 루프 차단과 가용성 보장 |

#### 한줄 요약
- 상향식 장애 진단, MSS 최적화, L7 방화벽 검사, RSTP 루프 방어로 운영한다.

## Ⅶ. 결론

- 현대 인터넷이 TCP/IP 4계층 프로토콜 스택으로 상용화되었음에도 불구하고 모든 네트워크 장비 설계와 트러블슈팅의 개념적 나침반 역할을 수행하는 **가장 근본적인 네트워크 아키텍처 참조 모델이자 장애 진단 표준 체계**로 자리잡았으며, 실무 운영 시에는 **L1 물리 케이블 확인부터 L7 WAF 페이로드 검증까지 이어지는 상향식(Bottom-Up) 진단 절차 준수, 터널링 시 PMTUD/MSS Clamping을 통한 MTU 단편화 방지, L2 RSTP 루프 차단**을 결합하여 복잡한 분산 네트워크의 가용성과 안정성을 완성

#### 한줄 요약
- OSI 7계층 모델은 7단계 모듈화와 캡슐화를 통해 이기종 통신을 보장하고 네트워크 설계와 장애 진단의 표준을 제공하는 핵심 참조 모델이다.
