## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **개방형 시스템 간 상호접속 7계층 모델(OSI 7-Layer Model)**: 통신 기능을 7단계로 표준화하여 삼성폰과 애플폰처럼 기종이 달라도 서로 통신을 주고받게 해주는 국제 참조 모델이다.
- **국제표준화기구(ISO)**: "네트워크는 이렇게 만들어라" 하고 전 세계 통신 규칙(표준)을 찍어내는 기구이다.

</details>

- 정의: 네트워크 통신 기능을 7개의 계층으로 모듈화하여, 이기종 장비 간의 호환성을 보장하는 국제 표준 참조 아키텍처인 **OSI 7-Layer Model**
- 배경: 제조사마다 통신 규격이 제멋대로여서, 시스코 장비와 타사 장비 간에 **통신이 불가능한 호환성 지옥**을 해결하기 위함

#### 한줄 요약

- 통신 과정을 7단계로 나눠서, 기종이 달라도 대화가 통하게 만든 국제 통신 규격이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **프로토콜 데이터 단위(PDU, Protocol Data Unit)**: 계층마다 "이건 내가 처리할 데이터야" 하고 도장을 찍어놓은 논리적인 택배 상자(데이터 블록)이다.
- **캡슐화/역캡슐화(Encapsulation/Decapsulation)**: 보낼 땐 작은 상자를 큰 상자에 계속 덧포장(캡슐화)하고, 받을 땐 겉포장부터 하나씩 뜯어보는(역캡슐화) 과정이다.

</details>

- **계층 독립성(Layer Interface)**: 하위 계층(랜선)이 바뀌어도 상위 계층(웹 브라우저) 코드는 고칠 필요가 없는 철저한 모듈화.
- **PDU 제어**: 주소, 오류 제어 등 계층별로 자기가 맡은 층의 헤더만 책임지는 엄격한 분업화.
- **캡슐화/역캡슐화**: 송신자는 포장하고 수신자는 뜯어서 원본 데이터를 완벽하게 복원하는 대칭 구조.

#### 한줄 요약

- 각 층마다 자기 할 일(PDU)만 하고 포장(캡슐화)해서 밑으로 넘기는 철저한 분업 시스템이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **매체 접근 제어(MAC, 2계층)**: 같은 방(네트워크) 안에 있는 컴퓨터들끼리 충돌 안 나게 랜선으로 데이터를 건네주는 하위 제어 역할이다.
- **인터넷 프로토콜(IP, 3계층)**: 서울에서 부산까지 논리적인 IP 주소를 보고 최적의 길(라우팅)을 찾아주는 내비게이션이다.
- **전송 제어 프로토콜(TCP, 4계층)**: 데이터가 가다가 유실되면 다시 보내달라고 멱살 잡고 확실하게 배달해 주는 우체국장이다.

</details>

```text
[ OSI 7계층 모듈화 아키텍처 ]

[ 7. 응용 계층 ] ── (HTTP, DNS) ──▶ 사용자 프로그램의 통신 인터페이스
[ 6. 표현 계층 ] ── (JPEG, SSL) ──▶ 데이터 압축, 암호화, 포맷 변환
[ 5. 세션 계층 ] ── (Socket, RPC) ─▶ 응용 프로세스 간 대화 제어 및 동기화
──────────────────────────────────────────── [상위: 데이터 생성]
[ 4. 전송 계층 ] ── (TCP, UDP) ───▶ 종단 간 신뢰성 보장 (포트 번호)
[ 3. 네트워크 계층 ] ─ (IP, 라우터) ─▶ 최적 경로 탐색 및 논리적 주소 지정
[ 2. 데이터링크 계층 ] (MAC, 스위치) ─▶ 인접 노드 간 물리적 전달 (에러 제어)
[ 1. 물리 계층 ] ── (케이블, 리피터) ▶ 0과 1의 비트를 전기 신호로 변환 전송
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **L7 응용 계층 (Application)** | 유저가 직접 만지는 웹 브라우저(HTTP)나 이메일(SMTP) 화면을 띄워줌 |
| **L6 표현 계층 (Presentation)**| 데이터가 깨지지 않게 압축하고 암호화(SSL/TLS)해서 공용어로 번역함 |
| **L5 세션 계층 (Session)** | 통신이 끊어지지 않게 연결 상태를 조율하고 복구함 |
| **L4 전송 계층 (Transport)** | 포트 번호(Port)로 프로세스를 찾아가고, 누락된 데이터 재전송(TCP)을 책임짐 |
| **L3 네트워크 계층 (Network)** | IP 주소를 보고 서울에서 부산까지 가장 빠른 길(라우팅)을 안내함 |
| **L2 데이터링크 계층 (Data Link)**| MAC 주소로 바로 옆 컴퓨터까지 안전하게 프레임(Frame)을 토스함 |
| **L1 물리 계층 (Physical)** | 데이터를 전기 신호(0과 1)로 바꿔서 구리선이나 광케이블로 쏴버림 |

#### 한줄 요약

- L1~L4는 짐을 배달하는 택배 기사고, L5~L7은 그 짐을 받아서 포장 까고 물건을 쓰는 소비자다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **세그먼트(Segment, L4)**: 4계층이 데이터에 포트 번호 딱지를 붙여서 잘라놓은 조각이다.
- **패킷(Packet, L3)**: 3계층이 세그먼트에 IP 주소를 발라서 만든 택배 상자이다.
- **프레임(Frame, L2)**: 2계층이 패킷 앞뒤에 MAC 주소와 에러 검사(FCS) 딱지를 붙인 튼튼한 포장 박스이다.

</details>

```text
[ OSI 7계층 캡슐화 및 역캡슐화 흐름 ]
┌──────────────────────────────┐
│ 송신자 (Application)           │
│ "안녕" (데이터 생성)         │
└──────────────┬───────────────┘
               ▼ (캡슐화 시작)
┌──────────────────────────────┐
│ [L4] TCP 헤더 부착 (세그먼트)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ [L3] IP 헤더 부착 (패킷)       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ [L2] MAC 헤더 부착 (프레임)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ [L1] 전기 신호로 쏴버림 (비트) │
├──────────────┬───────────────┤
│              ▼ (인터넷 통과)  │
└──────────────────────────────┘
(수신자는 역순으로 L1부터 L7까지 포장을 벗겨서 "안녕"을 읽음)
```

### 동작 원리

1. 데이터 생성 (L7~L5): 브라우저가 "안녕"이라는 메시지(Data)를 만듦.
2. 세그먼트 생성 (L4): "웹서버(80번 포트)로 가라"고 TCP 헤더를 붙임.
3. 패킷 생성 (L3): "목적지 IP 주소로 가라"고 IP 헤더를 덧붙임.
4. 프레임 생성 (L2): "옆집 라우터 MAC 주소로 넘겨라"고 포장함.
5. 비트 전송 (L1): 이 덩어리들을 0과 1의 전기 신호로 바꿔 선으로 쏨.

#### 한줄 요약

- 보낼 땐 위에서 아래로 헤더를 덧붙여 포장(캡슐화)하고, 받을 땐 아래서 위로 헤더를 뜯으며(역캡슐화) 데이터를 확인한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCP/IP 4계층 모델(TCP/IP Model)**: OSI 7계층이 교과서라면, TCP/IP 4계층은 7층을 4층으로 압축해서 실제 인터넷을 굴려 먹는 실전 압축 근육이다.

</details>

| 비교 항목 | **OSI 7계층 (이론적 교과서)** | **TCP/IP 4계층 (실전 압축 근육)** |
|:---|:---|:---|
| 성격 | 학술적이고 체계적인 **참조 모델** | 지금 우리가 쓰는 실제 인터넷 **구현 모델** |
| 계층 구성 | **7개 계층** (엄격하게 분리) | **4개 계층** (실용적으로 통합) |
| L5/L6 계층 | 세션(L5), 표현(L6) 계층 독립 | **응용 계층(L4)**에 싸잡아서 포함시킴 |
| L1/L2 계층 | 데이터링크(L2), 물리(L1) 분리 | **네트워크 액세스 계층(L1)**으로 묶어버림 |
| 주 활용 | "장애 났을 때 어디가 문제냐?" 따지는 **진단 기준** | 웹, 메일 등 실제 동작하는 **프로토콜 스택** |

#### 한줄 요약

- OSI는 학자들이 만든 완벽한 교과서고, TCP/IP는 해커와 공학자들이 만든 실전 매뉴얼이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상향식 장애 분석(Bottom-Up Troubleshooting)**: "인터넷 안 돼요" 할 때 냅다 서버 설정부터 까는 게 아니라, 랜선(L1) 꽂혔는지부터 확인하고 핑(L3) 때려보는 근본적인 트러블슈팅 순서이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| "인터넷이 안 돼요" (어디가 고장 났는지 모름) | 핑(L3) 때려보고 랜선(L1) 확인하는 **상향식 계층 장애 분석** 적용 | 원인 국소화 및 헛다리 짚기 방지 |
| VPN 헤더가 자꾸 덧붙어서 덩치가 커지다 패킷 터짐 | 네트워크 구간의 **최대 전송 단위(MTU)** 축소 조정 설정 | 덩치 초과로 인한 패킷 드롭 예방 |
| L3 방화벽만 믿고 있다가 웹(L7) 해킹 공격에 뚫림 | L7 앱 트래픽까지 까보는 **차세대 방화벽(NGFW) / WAF** 투입 | 응용 계층의 지능형 공격 원천 차단 |

#### 한줄 요약

- 네트워크 터지면 우왕좌왕하지 말고, L1(랜선)부터 L7(앱)까지 계층별로 쪼개서 점검해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **점검 시작점 결정(Starting Point Selection)**: 증상(Ping이 빠지면 L3, 웹만 안 열리면 L7)을 보고, 1층부터 뒤질지 7층부터 뒤질지 빠르게 눈치 챙기는 의사결정 체계이다.

</details>

- **점검 시작점 결정** 원칙에 따라, 증상 계층을 기준으로 **L1~L7 상향/하향식 추적**을 수행하여 네트워크 장애 복구 시간(MTTR)을 최소화하는 기조 확립함

#### 한줄 요약

- 네트워크 장애 복구의 핵심은 OSI 7계층이라는 지도를 펼치고 범인을 좁혀가는 거다.
