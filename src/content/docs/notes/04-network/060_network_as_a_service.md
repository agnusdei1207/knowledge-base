## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **서비스형 네트워크(Network as a Service, NaaS)**: 복잡한 네트워크 인프라 구축 없이 연결•보안•품질 기능을 Cloud형 API 및 온디맨드 구독 모델로 제공하는 네트워크 가상화 서비스 방식이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 개발자 및 상위 관리 플랫폼이 네트워크 자원의 주문•변경•해지 요청을 자동화된 프로그래밍 방식으로 제어하는 표준 호출 규격이다.

</details>

- 정의/개념: **NaaS**(Network as a Service)는 물리적 네트워크 장비 및 회선 조달 없이, 연결•보안•품질 기능을 표준화된 **API**(Application Programming Interface) 기반의 셀프 서비스 포털을 통해 실시간으로 주문, 변경, 관리하는 구독형 서비스이다.
- 배경/필요성: 기존 자체 인프라 구축(On-Premise) 방식은 장비 조달 및 개통 지연이 길고 초기 자본 투자(CapEx) 부담이 크며 대규모 멀티 클라우드 및 하이브리드 워크로드에 대한 신속한 확장 대응이 어려워 도입이 가속화되었다.

#### 한줄 요약

- 회선과 보안 장비 조달 없이 필요한 광역 연결 및 보안 기능을 소프트웨어 정의 방식으로 즉시 구독·확장하는 NaaS 수용 체계 적용.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **서비스 카탈로그(Service Catalog)**: 가입자가 즉시 주문 가능한 대역폭, 보안 기능, 품질 정책 및 노드 간 연결 조건의 표준화된 서비스 항목 목록이다.
- **서비스 수준 협약(Service Level Agreement, SLA)**: 공급자가 보장해야 하는 네트워크 가용성, 지연 시간, 손실률 목표 및 미달 시의 손해 배상 책임을 명시한 상호 계약 체계이다.
- **사용량 과금(Usage-based Billing / Pay-per-use)**: 고정 자산 정액제 방식이 아닌, 실제 점유한 대역폭, 트래픽 전송량 및 이용 기간에 비례하여 비용을 산정하는 종량제 모델이다.

</details>

- **서비스 카탈로그** 및 API 인터페이스를 기반으로 주문부터 프로비저닝, 변경 및 해지 단계까지 전 과정을 자동화한다.
- 이용자의 서비스 의도(Intent) 기반 요구사항을 분석하여 소프트웨어 정의 제어 평면을 통해 종단 간 최적 경로 및 보안 정책으로 자동 변환한다.
- 명확한 **SLA** 체계를 통한 서비스 품질을 보장하며, **사용량 과금** 모델을 적용하여 운영 비용(OpEx) 최적화 유용성을 확보한다.

#### 한줄 요약

- 서비스 카탈로그와 SLA 보장, 종량제 과금 구조를 융합하여 온디맨드 네트워크 가황성을 극대화하는 소프트웨어 중심 제어 원칙 준수.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **오케스트레이터(Orchestrator)**: 상위 API 주문 의도를 물리/가상 네트워크 장비의 설정, 경로 계산 및 가상 네트워크 기능(VNF) 배치 작업 순서로 자동 변환하는 중앙 제어 시스템이다.
- **네트워크 패브릭(Network Fabric)**: 물리적 회선 및 가상 Swtich/Router 세그먼트를 융합하여 단일 논리적 가상 네트워크 서비스 경로를 형성하는 하부 전송 인프라이다.

</details>

- **오케스트레이터**는 추상화된 주문 의도를 장비별 설정 명령으로 자동 변환하고, **네트워크 패브릭**은 종단 간 동적 터널링과 보안 정책을 유연하게 실행한다.

```text
NaaS
├─ 서비스 접점: 포털•API (Portal & API)
├─ 제어 기능: 오케스트레이터 (Orchestrator)
├─ 실행 기능
│  ├─ 네트워크 패브릭•기능 (Network Fabric & VNF)
│  └─ 서비스 에지 (Service Edge)
└─ 관리 기능: 관측•SLA•과금 (Observability, SLA & Billing)
```

| 구성요소 | 역할 및 핵심 기능 |
|:---|:---|
| **포털•API (Portal & API)** | 서비스 주문, 변경, 실시간 상태 조회 및 제어 인터페이스 제공 |
| **오케스트레이터 (Orchestrator)** | 서비스 의도 기반 경로 계산, 장비 프로비저닝 및 VNF 체이닝 자동화 |
| **네트워크 패브릭•기능 (Network Fabric & VNF)** | VXLAN/MPLS/SD-WAN 터널 생성, 트래픽 라우팅, FW/IDS 보안 기능 실행 |
| **서비스 에지 (Service Edge)** | 지사, 본사 데이터센터 및 멀티 클라우드 접속 종단 접속점 제공 |
| **관측•SLA•과금 (Observability, SLA & Billing)** | 실시간 트래픽 관측, SLA 가용성 측정 및 종량제 비용 자동 산정 |

#### 한줄 요약

- 오케스트레이터 중심 제어 평면과 데이터 패브릭, SLA 관측 시스템으로 연계된 통합 서비스 오케스트레이션 아키텍처 구현 필수.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **서비스 의도(Service Intent)**: 이용자가 요구하는 종단 간 대역폭, 보안 등급, 지연 시간 조건을 장비 독립적 언어로 선언한 주문 사양서이다.
- **소프트웨어 정의 광역망(Software-Defined Wide Area Network, SD-WAN)**: 멀티 벤더 회선 및 복합 트래픽 정책을 중앙 제어 소프트웨어로 최적화하는 WAN 가상화 기술이다.
- **보안 액세스 서비스 에지(Secure Access Service Edge, SASE)**: SD-WAN 네트워크 연결 기능과 클라우드 기반 SWG, CASB, ZTNA 보안 기능을 단일 서비스 에지에서 융합 제공하는 플랫폼 architecture이다.
- **경로•기능 설정(Path and Function Provisioning)**: 추상화된 의도를 실제 물리 회선, SD-WAN 터널, 가상 방화벽 정책 구성으로 맵핑하는 자동화 단계이다.
- **품질•사용량 지표(QoS and Usage Metrics)**: Latency, Jitter, Packet Loss, Bandwidth 전송량을 실시간 수집한 데이터 세트이다.
- **SLA•과금 상태(SLA & Billing Status)**: 측정된 지표 기반의 SLA 준수 판정 및 사용률 계산 결과이다.
- **서비스 상태(Service State / Status)**: 현재 경로의 활성화 여부, 트래픽 통계 및 청구 예정 금액을 포함한 통합 리포팅 정보이다.

</details>

```text
서비스 주문 (Service Order)
      │
      ▼
1. 서비스 의도 검증 (Service Intent Verification)
      │
      ▼
2. 경로•기능 자동 설정 (Path & VNF Provisioning)
      │
      ▼
개통 완료 및 터널 활성화 (Service Provisioned)
      │
      ▼
반복 운영 주기 (Continuous Operation)
      │
      ▼
3. 품질•사용량 지표 수집 (Metrics Collection)
      │
      ▼
4. SLA 준수 평가 및 과금 산정 (SLA & Billing Evaluation)
      │
      ▼
5. 서비스 대시보드 제공 (Dashboard & Alerting)
```

### 동작 원리

1. **서비스 의도 검증**: 사용자 요청 속성과 정책 충돌 여부 및 인프라 대역폭 여유량을 검증한다.
2. **경로•기능 자동 설정**: 오케스트레이터가 **SD-WAN** 터널, **SASE** 보안 게이트웨이 및 언더레이 회선을 자동으로 맵핑 및 적용한다.
3. **품질•사용량 지표 수집**: 데이터 패브릭 상의 **품질•사용량 지표**를 실시간으로 모니터링한다.
4. **SLA 준수 평가 및 과금 산정**: 수집된 지표를 기반으로 **SLA** 달성률 평가 및 실시간 과금을 산정한다.
5. **서비스 대시보드 제공**: 가입자 포털에 **서비스 상태** 및 헬스 체크 결과를 가시화한다.

#### 한줄 요약

- 의도 분석 기반 프로비저닝과 실시간 메트릭 수집, SLA 판정 루프가 선순환되는 자동화 프로세스 적용.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **공급자 종속(Vendor Lock-in)**: 특정 NaaS 사업자의 전용 API, 데이터 모델 및 프로토콜 사용으로 인해 다른 서비스 공급자로 전환 시 막대한 이관 비용이 발생하는 상태이다.

</details>

| 네트워크 제공 방식 | NaaS (Network as a Service) | 자체 구축 (On-Premise) | 관리형 네트워크 (Managed Network) |
|:---|:---|:---|:---|
| **적용 기준** | 트래픽 변동성 높음, 신속한 지점 확장 필요 | 최고 수준의 보안 및 자산 직접 통제 필요 | 자산은 소유하되 전문 운영 인력 부재 |
| **핵심 특징** | API 중심 온디맨드 구독, 무자산 오케스트레이션 | 전용 장비 조달, 직접 케이블링 및 설정 | 장비 구매 후 전문 벤더에 운영 위탁 |
| **비용 구조** | 가변 운영비(OpEx) 중심 종량제 | 고정 자본비(CapEx) 및 유지보수비 | CapEx 구매 + 고정 운영 대행료 |
| **주요 한계** | 사업자 API **공급자 종속**, 사용량 급증 시 비용 증가 | 장비 조달/증설 지연, 초기 투자 비용 과다 | 변경 반영 속도 저하, 책임 경계 모호 |

> 요약: 높은 유연성과 무자산 기반 신속 확장이 필요한 경우 **NaaS**, 인프라 직접 통제권이 최우선인 경우 자체 구축, 운영 위탁에는 관리형 모델을 선정한다.

#### 한줄 요약

- 기업의 네트워크 자산 정책, 보안 통제 수준, 운영 역량에 따른 NaaS vs 자체 구축 vs 관리형 모델 최적선택 체계 적용.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **종단 측정점(End-to-End Measurement Point)**: 고객 서비스 접속 구간 양 끝단에 위치시켜 실제 체감 품질 및 SLA 위반 책임을 객관적으로 산출하는 모니터링 지점이다.
- **구성 내보내기(Configuration Export)**: 특정 벤더 NaaS 환경의 네트워크 정책 및 접속 설정을 표준화된 형식(JSON/YAML)으로 이관 가능하게 추출하는 기능이다.

</details>

| 실무 문제점 | 발생 원인 | 해결 대책 | 기대 효과 |
|:---|:---|:---|:---|
| **장애 책임 공방** | 멀티 클라우드 및 벤더 구간 경계에서 객관적 모니터링 부재 | **종단 측정점** 배치 및 SLA 세부 지표(지연/손실) 측정 명시 | 구간별 객관적 장애 원인 규명 및 핑퐁 현상 방지 |
| **예산 초과 위험** | 트래픽 폭증 시 종량제 과금에 따른 OpEx 급증 | 최대 월간 예산 한도(Cap) 설정 및 단계별 사용량 경보 자동화 | 예측 불가능한 비상용 트래픽 비용 폭증 사전 예방 |
| **벤더 종속성** | 특정 NaaS 사업자의 전용 API 및 캡슐화 포맷에 예속 | 오픈 API 규격 준수 사업자 선정 및 **구성 내보내기** 체계 구성 | 타 NaaS 또는 하이브리드 환경으로의 유연한 이관 가능성 확보 |

#### 한줄 요약

- 종단 측정점 기반 SLA 검증, 예산 cap 제한, 표준 API 기반 이관성 확보를 통한 실무 리스크 제어 체계 구축.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **네트워크 제공 방식(Network Delivery Models)**: 변동성, 투자 비용, 통제권 요소를 다각도로 평가하여 NaaS, On-Premise, Managed Service 중 최적을 선정하는 의사결정 체계이다.

</details>

- **네트워크 제공 방식** 수립 시 급변하는 클라우드 연동 및 지사 확장 환경에는 **NaaS**를 적극 채택하고, SLA 검증 자동화와 벤더 종속 방지 대책을 병행하는 지능형 가상 네트워킹 수용 체계 적용.

#### 한줄 요약

- 소프트웨어 정의 제어 및 온디맨드 API 가상화를 활용한 멀티 클라우드 시대 NaaS 통합 아키텍처 구현 필수.
