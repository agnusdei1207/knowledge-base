## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서비스형 네트워크(Network as a Service, NaaS)**: 기업이 물리적 라우터, 스위치, 방화벽 인프라를 직접 구매·구축하지 않고, 통신사 또는 클라우드 사업자가 가상화(SDN/NFV)하여 제공하는 광역망(WAN), 보안, 데이터센터 네트워크 자원을 온디맨드(On-Demand) 구독형으로 이용하는 서비스 모델.
- **자본 지출(CapEx) 및 운영 비용(OpEx)**: 네트워크 하드웨어 자산 구매 및 초기 구축에 투입되는 고정 자본 비용(CapEx)과, 사용량에 비례하여 월별 과금되는 가변 운영 비용(OpEx).

</details>

- 정의/개념: 하드웨어 소유 중심의 전통적 네트워크 구축 방식을 탈피하여, **SDN/NFV 및 클라우드 오케스트레이터** 기반으로 네트워크 연결성과 보안 기능을 API 및 셀프서비스 포털을 통해 제공하는 **구독형 네트워크 서비스(NaaS)**
- 배경/필요성: 지사 확장 및 클라우드 마이그레이션 시 물리 장비 도입에 따른 긴 리드 타임(수개월)과 막대한 초기 투자 비용(CapEx)을 절감하고, 트래픽 수요에 따른 탄력적 대역폭 확장을 실현할 요구

#### 한줄 요약
- 물리 장비 구매 없이 SDN/NFV 기반 가상 네트워크와 보안 기능을 구독형(OpEx)으로 이용한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **서비스 수준 협약(SLA) 보증**: 가용성(99.999%), 지연 시간(RTT), 지터(Jitter), 패킷 손실률 등 네트워크 품질 지표를 계약으로 명문화하고 위반 시 보상하는 계약 체계.
- **클라우드 네이티브 오케스트레이션**: RESTful API 또는 인프라 코드화(IaC)를 통해 글로벌 전송망, 가상 사설망(VPN), 보안 정책을 수 분 내에 자동 프로비저닝하는 기능.

</details>

- **재무 구조 혁신 (CapEx $\rightarrow$ OpEx 전환)**: 하드웨어 구매 비용과 감가상각 부담을 제거하고 실제 사용 대역폭에 따른 종량제(Pay-as-you-go) 비용 모델 적용
- **온디맨드 민첩성(Agility)**: 웹 포털 및 API 호출을 통해 글로벌 지사 연결 및 클라우드 인터커넥트(Direct Connect)를 수 분 내에 개통
- **통합 보안 및 네트워크 융합(SASE)**: SD-WAN 오버레이 라우팅과 클라우드 보안(SWG, CASB, ZTNA)을 단일 NaaS 플랫폼으로 통합 제공

#### 한줄 요약
- OpEx 비용 구조 전환, API 기반 수 분 내 온디맨드 개통, SD-WAN/SASE 통합 보안을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **중앙 서비스 오케스트레이터(Central Orchestrator)**: 고객 포털의 서비스 요청(의도, Intent)을 해석하여 하위 물리/가상 네트워크 인프라에 적절한 구성을 자동 생성·주입하는 제어 두뇌.
- **가상 데이터 패브릭(Data Fabric / SD-WAN)**: 인터넷, MPLS, 5G 등 이종 언더레이 회선을 번들링하여 가상 오버레이 터널을 형성하는 고성능 전송 계층.

</details>

```text
[ 1. 고객 인터페이스 계층 (Customer Portal / REST API) ]
   │ (온디맨드 대역폭 요청, 서비스 의도: Intent 주입)
   ▼
[ 2. 중앙 오케스트레이션 및 제어 계층 (NaaS Controller) ]
   ├─ 서비스 카탈로그 / 인텐트 해석기
   ├─ SDN 컨트롤러 (트래픽 경로 연산)
   └─ NFV 오케스트레이터 (가상 방화벽/SD-WAN VNF 배치)
   ▼
[ 3. 데이터 패브릭 계층 (SD-WAN / SASE / Cloud Interconnect) ]
   ├─ 지사 엔드포인트 ──▶ [ IPsec / TLS 오버레이 터널 ] ──▶ 본사 / 클라우드 VPC
   └─ 클라우드 보안 엣지 (SWG / CASB / FWaaS)
   ▼
[ 4. 텔레메트리 및 과금 계층 (SLA Monitoring & Billing) ]
```

선의 의미: 고객의 포털 주문이 오케스트레이터로 전달되어 가상 데이터 패브릭을 구성하고, 실시간 텔레메트리를 통해 SLA 검증 및 종량제 과금이 수행되는 구조

| 구성요소 | 책임 및 역할 | 비고 |
|:---|:---|:---|
| **셀프서비스 포털 / API** | 고객이 대역폭, QoS, 토폴로지 요구조건(Intent)을 직접 설정하는 창구 | NBI 인터페이스 |
| **중앙 오케스트레이터** | 주문된 Intent를 분석하여 SDN/NFV 인프라에 라우팅 및 보안 규칙 자동 프로비저닝 | Control Plane |
| **가상 데이터 패브릭** | SD-WAN, IPsec 터널, SASE 보안 모듈을 통해 실제 패킷을 라인 레이트로 전달 | Data Plane |
| **SLA 감시 및 빌링** | E2E 지연/패킷 손실을 실시간 계측하여 SLA 위반을 감시하고 사용량 기반 과금 | Billing / AIOps |

#### 한줄 요약
- 고객 포털, 중앙 오케스트레이터, 데이터 패브릭, SLA 감시/과금 모듈이 유기적으로 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **의도 기반 네트워킹(Intent-Based Networking, IBN)**: "지사 간 1Gbps 보안 터널 개통"과 같은 상위 비즈니스 요구(Intent)를 입력하면 시스템이 하부 네트워크 구성 스크립트로 자동 번역·집행하는 기술.

</details>

```text
1. 고객이 NaaS 관리 포털 또는 API를 통해 네트워크 개통 요청(대역폭, 지사 위치, SLA 등급) 입력
            │
            ▼
2. 중앙 오케스트레이터가 비즈니스 의도(Intent)를 파싱하여 최적 전송 경로 및 VNF 배치 계획 수립
            │
            ▼
3. SDN/NFV 엔진이 소프트웨어 기반 가상 라우터(vEdge) 및 보안 정책(FWaaS)을 자동 프로비저닝
            │
            ▼
4. 지사-본사-클라우드 간 SD-WAN 암호화 오버레이 터널이 즉시 수립되어 트래픽 전송 개시
            │
            ▼
5. 실시간 텔레메트리 프로브가 SLA 지표를 24시간 계측하고 월별 종량제 사용량 데이터 집계
```

**동작 원리**

1. **서비스 요청**: 고객이 포털에서 출발지/목적지와 요구 성능(SLA)을 선택
2. **템플릿 변환**: 오케스트레이터가 사전 정의된 IaC 템플릿(Terraform/Ansible)과 SDN 룰 생성
3. **가상 인프라 배포**: 엣지 게이트웨이 및 클라우드 PoP에 가상 네트워크 인스턴스를 즉각 기동
4. **터널 자동 연결**: 제로 터치 프로비저닝(ZTP)으로 지사 장비가 켜지면 중앙 컨트롤러와 자동 터널링
5. **폐루프 보증**: 전송 지연 발생 시 AI 기반 트래픽 엔지니어링이 자동으로 우회 경로를 절체하고 과금 데이터 산출

#### 한줄 요약
- 포털 주문, Intent 해석, SDN/NFV 자동 프로비저닝, 오버레이 터널 개통, SLA 감시 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **벤더 종속(Vendor Lock-in)**: 특정 클라우드/통신사의 독점 API 및 비표준 구성 모델에 종속되어 타사 서비스로의 이전이 곤란해지는 위험.

</details>

| 비교 항목 | 서비스형 네트워크 (NaaS) | 전통적 온프레미스 네트워크 |
|:---|:---|:---|
| **자산 소유권** | **서비스 제공자(통신사/CSP) 소유** | **기업 자체 물리 자산 소유** |
| **비용 구조** | **월별 종량제 운영 비용 (OpEx)** | **대규모 초기 하드웨어 구매 비용 (CapEx)** |
| **망 개통 리드 타임** | **수 분 ~ 수 시간 (소프트웨어 자동화)** | 장비 구매, 배송, 설치로 **수 주 ~ 수개월** |
| **확장성 및 유연성** | 포털 클릭을 통한 **즉각적 스케일업/다운** | 장비 증설 및 물리 교체 공사 요구 |
| **유지보수 책임** | 제공업체가 24x7 패치, HW 교체, SLA 보증 | 기업 내부 네트워크 엔지니어가 직접 전담 |

#### 한줄 요약
- NaaS는 OpEx 기반 온디맨드 확장성과 유지보수 외주화를 제공하며, 온프레미스는 물리적 통제권을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **종단간 활성 프로빙(E2E Active Probing)**: 고객 엔드포인트부터 클라우드 서비스 종단까지 주기적으로 합성 트래픽(Synthetic Traffic)을 발송하여 패킷 손실과 RTT를 측정하는 모니터링 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복합 클라우드/통신사 연동 구간 장애 시 책임 소재 불명확(Finger-Pointing) | **종단간(E2E) 활성 프로빙 및 독립 디지털 경험 모니터링(DEM)** 도입 | 장애 발생 도메인 즉각 식별 및 명확한 SLA 위반 보상 청구 |
| 급격한 트래픽 스파이크로 인한 예상치 못한 월말 종량제 요금 폭증 | **대역폭 상한선(Bandwidth Cap) 설정** 및 단계별 임계치 알람 구성 | 예측 불가능한 요금 초과 방지 및 통신 예산 통제력 확보 |
| 특정 NaaS 사업자 전용 API 및 구성 모델에 대한 종속(Vendor Lock-in) | **개방형 표준 API(MEF LSO) 채택** 및 IaC(Terraform) 기반 추상화 | 다중 NaaS 제공자 간 원활한 이전 및 멀티 클라우드 유연성 확보 |

#### 한줄 요약
- E2E 프로빙으로 책임 경계를 명확화하고, Bandwidth Cap으로 비용 폭증을 방지하며, MEF LSO 표준으로 벤더 종속을 차단한다.

## Ⅶ. 결론

- 클라우드 전환 가속화와 분산 근무 환경에 대응하여 네트워크 민첩성과 비용 효율을 극대화하기 위해 **NaaS 구독 모델**을 전략적으로 도입하되, 통신 장애 및 벤더 종속 리스크를 제어하기 위해 **MEF LSO 표준 API 기반 다중 사업자 전략**, **E2E 성능 감시**, **Zero Trust SASE 통합 보안 체계**를 병행 구축하여 탄력적인 엔터프라이즈 통신 인프라를 완성

#### 한줄 요약
- SDN/NFV 기반 NaaS 구독 모델과 SASE 보안을 융합하여 민첩하고 유연한 엔터프라이즈 네트워크를 구현한다.
