## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NaaS (Network as a Service)**: 물리 네트워크 장비를 직접 구축하지 않고 SDN/NFV 기반으로 가상화된 네트워크 연결성과 보안을 클라우드 구독형으로 이용하는 모델.
- **CapEx vs OpEx**: 대규모 초기 하드웨어 투자 비용(CapEx)과 사용량에 비례하여 지불하는 월별 가변 운영 비용(OpEx).

</details>

- 정의/개념: 물리 장비 소유 없이 **SDN/NFV 가상화 기반으로 WAN 연결성, 보안, 클라우드 인터커넥트를 API 및 포털로 온디맨드 제공하는 구독형 서비스 모델**
- 배경/필요성: 온프레미스 물리 장비는 지사·회선마다 **수개월의 도입 리드 타임과 선투자(CapEx)**를 반복 부담하므로, 사업자가 이미 구축한 공용 인프라 위에 구독형 가상 네트워크 계층을 얹어 장비 조달·설치 단계 자체를 생략

#### 한줄 요약
- CapEx를 OpEx로 전환하고, API 기반으로 수 분 내에 글로벌 네트워크와 보안을 온디맨드 개통한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **On-Demand Agility (온디맨드 민첩성)**: 물리 공사 없이 웹 콘솔 클릭이나 API 호출로 지사 간 SD-WAN 및 클라우드 다이렉트 커넥트를 수 분 내 개통하는 특성.
- **SASE (Secure Access Service Edge)**: SD-WAN 광역 연결성과 클라우드 보안(SWG, CASB, ZTNA)을 단일 NaaS 플랫폼으로 융합 제공하는 아키텍처.

</details>

- **재무 구조 혁신 (CapEx $\rightarrow$ OpEx 전환)**: 하드웨어 구매 및 감가상각을 제거하고 **사용량 기반 종량제(Pay-as-you-go) 적용**
- **온디맨드 민첩성(Agility)**: 웹 포털 및 API 호출을 통해 글로벌 지사 연결 및 클라우드 인터커넥트를 **수 분 내 개통**
- **통합 보안 및 네트워크 융합(SASE)**: SD-WAN 오버레이 라우팅과 클라우드 보안(SWG, CASB, ZTNA)을 단일 플랫폼으로 통합

#### 한줄 요약
- OpEx 비용 구조 전환, API 기반 수 분 내 온디맨드 개통, SD-WAN/SASE 통합 보안을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Central Orchestrator**: 고객의 주문(Intent)을 해석하여 하위 SDN 컨트롤러와 NFVI에 라우팅 및 가상 방화벽 규칙을 자동 주입하는 제어 두뇌.

</details>

```text
[NaaS 구성]
|-- 셀프서비스 포털 / API
|-- 중앙 오케스트레이터
|-- 가상 데이터 패브릭
`-- SLA 감시 및 빌링
```

선의 의미: 고객의 포털 주문이 오케스트레이터로 전달되어 가상 데이터 패브릭을 구성하고 실시간 텔레메트리로 SLA 검증 및 종량제 과금이 수행되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **셀프서비스 포털 / API**| 고객이 대역폭, QoS, 토폴로지 요구조건(Intent)을 **직접 설정하고 셀프 주문하는 창구** | NBI 인터페이스 |
| **중앙 오케스트레이터** | 주문된 Intent를 분석하여 **SDN/NFV 인프라에 라우팅 및 보안 규칙 자동 프로비저닝** | Control Plane |
| **가상 데이터 패브릭** | **SD-WAN, IPsec 터널, SASE 보안 모듈을 통해 실제 패킷을 라인 레이트로 전달** | Data Plane |
| **SLA 감시 및 빌링** | E2E 지연/패킷 손실을 실시간 계측하여 **SLA 위반을 감시하고 사용량 기반 종량 과금** | AIOps / Billing |

#### 한줄 요약
- 중앙 오케스트레이터가 고객의 주문 의도와 물리 데이터 패브릭 사이에 끼어들어, 고객이 직접 수행하던 장비 조달·구성 작업을 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IBN (Intent-Based Networking)**: "지사 간 1Gbps 보안 터널 개통"과 같은 고수준 비즈니스 의도를 하부 네트워크 스크립트로 자동 번역 집행하는 기술.

</details>

```text
NaaS 주문 및 온디맨드 자동 프로비저닝 파이프라인
        │
   1. [포털 서비스 주문] 고객이 웹 콘솔 또는 API로 대역폭, 거점, 보안 등급(Intent) 입력
        │
   2. [의도(Intent) 파싱] 중앙 오케스트레이터가 비즈니스 의도를 해석하여 IaC 배포 청사진 생성
        │
   3. [SDN/NFV 가상 인프라 배포] 엣지 및 클라우드 PoP에 가상 라우터(vEdge) 및 방화벽(FWaaS) 기동
        │
   4. [오버레이 터널 자동 연결] ZTP(Zero Touch)로 지사 장비가 켜지면 중앙 컨트롤러와 터널 즉시 개통
        │
   ▼
5. [SLA 폐루프 보증 및 과금] 24x7 텔레메트리 감시로 SLA를 보증하고 월별 종량제 사용량 데이터 집계
```

#### 한줄 요약
- 주문부터 SLA 보증까지가 사람 개입 없는 폐루프로 묶이므로, 개통 리드 타임이 장비 조달 기간이 아니라 오케스트레이터의 배포 시간으로 결정된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **NaaS (구독형)** vs **전통적 온프레미스 (소유형)**: 클라우드 가상화 구독 모델과 물리 하드웨어 자산 소유 모델.

</details>

| 비교 항목 | 서비스형 네트워크 (NaaS) | 전통적 온프레미스 네트워크 |
|:---|:---|:---|
| **자산 소유권** | **서비스 제공자(통신사/CSP) 소유** | **기업 자체 물리 하드웨어 자산 소유** |
| **비용 구조** | **월별 가변 운영 비용 (OpEx 종량제)** | **대규모 초기 하드웨어 구매 비용 (CapEx)**|
| **망 개통 리드 타임**| **수 분 ~ 수 시간 (소프트웨어 자동화)** | 장비 발주, 배송, 설치로 **수 주 ~ 수개월**|
| **확장성 및 유연성**| 포털 클릭을 통한 **즉각적 탄력 확장** | 장비 증설 및 물리 케이블링 공사 필요 |
| **유지보수 책임** | 제공업체가 24x7 패치, HW 교체, SLA 보증 | 기업 내부 전담 엔지니어가 직접 수행 |

#### 한줄 요약
- NaaS는 OpEx 기반 온디맨드 확장성과 유지보수 외주화를 제공하며, 온프레미스는 물리적 통제권을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MEF LSO (Lifecycle Service Orchestration)**: 서로 다른 통신사와 NaaS 사업자 간의 상호 연동 및 서비스 자동화를 위한 개방형 표준 API 프레임워크.
- **DEM (Digital Experience Monitoring)**: 사용자 엔드포인트부터 SaaS 앱까지의 E2E 네트워크 체감 품질을 지속 프로빙하는 모니터링 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복합 클라우드/통신사 연동 구간 장애 시 책임 공방(Finger-Pointing) | **E2E 활성 프로빙 및 `디지털 경험 모니터링(DEM)` 도입** | 장애 발생 구간 즉각 특정 및 SLA 위반 보상 청구 |
| 급격한 트래픽 스파이크로 인한 예상치 못한 월말 종량제 요금 폭증 | **`대역폭 상한선(Bandwidth Cap)` 설정 및 단계별 임계치 알람** | 예측 불가능한 요금 초과 방지 및 예산 통제력 확보 |
| 특정 NaaS 사업자 전용 API 및 구성 모델 종속(Vendor Lock-in) | **개방형 표준 API(`MEF LSO`) 채택 및 IaC(Terraform) 추상화** | 다중 사업자 간 원활한 전환 및 멀티 클라우드 유연성 확보 |
| 공용 인터넷 오버레이 터널 경유 시 원격 근무자 데이터 유출 위협 | **ZTNA(제로 트러스트 네트워크 접속) 및 `상시 mTLS 암호화`** | 비인가 단말 차단 및 엔드투엔드 데이터 기밀성 유지 |

#### 한줄 요약
- DEM 모니터링, Bandwidth Cap, MEF LSO 표준 API, ZTNA 제로 트러스트 보안으로 운영한다.

## Ⅶ. 결론

- 탄력 확장은 **NaaS**, 물리 통제권이 우선이면 **온프레미스** 선택

#### 한줄 요약
- NaaS는 SDN/NFV 기반 구독 모델과 SASE 보안을 융합하여 민첩성과 유연성을 제공하는 차세대 기업 네트워크 패러다임이다.
