## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NaaS (서비스형 네트워크, Network as a Service)**: 비싼 시스코 라우터를 회사 돈으로 사서 깔지 않고, 클라우드처럼 월정액 내고 "회선 10기가짜리 뚫어줘" 하면 1분 만에 개통되는 렌탈형 네트워크 서비스다.
- **SDN / NFV (소프트웨어화)**: 물리 장비를 사는 대신 통신사 중앙에서 소프트웨어로 가상 라우터랑 방화벽을 뚝딱 만들어내서, 고객한테 렌탈(NaaS) 해줄 수 있게 만드는 핵심 밑바탕 기술이다.

</details>

- 정의: **NaaS** 기반 물리 라우터나 스위치를 직접 사지 않고, SDN과 NFV 기술로 만들어진 통신사/클라우드의 가상 네트워크망을 온디맨드(On-Demand) 형태로 구독해 빌려 쓰는 서비스 모델이다.
- 배경: 본사랑 지사 연결하려고 비싼 장비 사고 랜선 깐다고 초반에 수억씩 박고(CapEx) 한 달씩 기다려야 하니까, **그냥 필요할 때 웹에서 버튼 눌러 빌려 쓰고 매달 쓴 만큼만 돈 내려고(OpEx) 등장했다.** #### 한줄 요약

- 수억짜리 장비를 내 돈 주고 사는 대신, 통신사가 만들어 놓은 가상 네트워크망을 넷플릭스처럼 렌탈해서 쓰는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CapEx / OpEx (비용 구조)**: 장비 사느라 초반에 수억씩 목돈(CapEx) 꼬라박는 걸 버리고, 매달 쓴 대역폭만큼만 렌탈비(OpEx)로 퉁치는 가성비 쩌는 지출 구조다.
- **SLA (서비스 수준 협약)**: 통신사가 "속도 1기가 무조건 보장하고, 끊기면 돈 물어줄게"라고 약속하는 강력한 품질 보증서다. NaaS의 생명줄이다.

</details>

- **목돈 대신 월세 (OpEx 전환)**: 장비 구매랑 감가상각 신경 쓸 필요 없이, 접속자 몰리면 대역폭 쫙 늘리고 빠지면 줄이면서 구독료 비용을 씹어 먹는다.
- **온디맨드 원클릭 개통**: 장비 배송 오길 한 달씩 기다릴 필요 없이, 웹 포털에서 API 버튼만 누르면 5분 만에 본사랑 지사 연결 망이 싹 다 개통된다.
- **글로벌 오케스트레이션 제어**: 전 세계 어디에 지사를 세우든 중앙 대시보드(오케스트레이터) 하나로 모든 보안 정책이랑 라우팅을 강력히 똑같이 통제한다.

#### 한줄 요약

- 목돈 안 박고 월세(OpEx) 내며, 웹에서 클릭 한 번이면 당일 날 전 세계 망이 싹 다 개통되는 게 핵심 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **서비스 포털 (API)**: 우리가 "여기서 저기 부산 지사까지 10기가 뚫어!"라고 주문을 넣는 웹 대시보드 쇼핑몰이다.
- **중앙 오케스트레이터 (두뇌)**: 쇼핑몰에서 주문 들어오면, 뒤에서 가상 라우터랑 방화벽을 뚝딱뚝딱 조립해서 납품하는 공장장이다.

</details>

```text
[ NaaS 렌탈망 직관적 비교 구조 ]

[ 1. 가입자 포털 (대시보드 / API) ] ── (고객: 부산 지사 10기가 회선 뚫어주셈)
      │
      ▼
[ 2. 중앙 오케스트레이터 (두뇌) ] ── (공장장: 오케이. 부산 쪽에 가상 라우터 조립 시작)
      │
      ▼
[ 3. 융합 데이터 패브릭 (SD-WAN / SASE) ] ── (실제로 패킷이 날아다니는 가상 고속도로망)
      │
      ▼
[ 4. 과금 및 SLA 감시 (빌링 시스템) ] ── (통신사: 속도 정상. 이번 달 요금 10만 원 청구!)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **서비스 포털 / API** | 고객이 대시보드 열어서 **대역폭 올리고 내리면서 주문하는 쇼핑몰 창구** | Interface |
| **중앙 오케스트레이터** | 주문받고 밑에 깡통 서버들한테 **"가상 라우터 깔고 망 뚫어" 명령하는 공장장** | Orchestrator |
| **데이터 패브릭 (망)** | 실제로 패킷이 날아다니는 **가상의 고속도로 인프라 (SD-WAN, 방화벽 등)** | Fabric |
| **SLA 감시 및 과금** | 끊기는지 안 끊기는지 24시간 핑 쏘면서 **월말에 요금 청구서 날리는 독촉장** | Billing |

#### 한줄 요약

- 포털에서 주문하면 $\to$ 공장장이 가상 라우터를 깔고 망을 뚫어준 뒤 $\to$ 월말에 감시자가 청구서를 날리는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **서비스 의도 (Intent)**: "OSPF 메트릭 10.." 같은 복잡한 명령어 말고, "본사용 트래픽은 가장 빠른 길로 쏴"처럼 사람이 쓰는 말로 쿨하게 주문하는 거다.
- **SD-WAN / SASE (융합망)**: NaaS가 납품하는 알맹이로, 선 꼬임 없이 똑똑하게 길 찾아주는 망(SD-WAN)과 클라우드 보안(SASE)의 개사기 합체본이다.

</details>

```text
[ NaaS 원클릭 망 개통 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [포털에서 서비스 주문 (Intent)]
│ (고객: 야 부산 지사 회선 좀 뚫어줘!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [오케스트레이터 의도 파악]│
│ (공장장: 오케이. 부산 쪽 가상 라우터 킨다)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [SD-WAN 패브릭 자동 개통] │
│ (망: 5분 만에 본사-부산 지사 터널 뚫림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [품질 감시 및 SLA 측정]   │
│ (감시자: 1기가 속도 보장 잘 되나 핑 쏴봄)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [월말 종량제 요금 청구]   │
│ (통신사: 이번 달 대역폭 쓴 만큼만 요금 내라)
└──────────────────────────────┘
```

### 동작 원리

1. 주문 접수: 고객이 포털에 들어가서 원하는 대역폭이랑 보안 등급(Intent)을 찍어 넣음.
2. 의도 파악 및 자원 할당: 중앙 오케스트레이터가 주문을 까보고 가상 장비들(VNF)을 어디다 깔지 계산함.
3. 개통 뚝딱: SD-WAN 터널이랑 방화벽 세팅이 원격으로 스르륵 밀고 들어가서 수분 내로 개통 완료됨.
4. SLA 체크: 계약된 속도랑 핑(지연 시간)이 제대로 나오는지 통신사가 텔레메트리로 24시간 감시함.
5. 요금 청구: 쓴 만큼 쪼개서 다음 달에 월세 청구서가 날아옴.

#### 한줄 요약

- 의도 주문 $\to$ 공장장 해석 $\to$ 망 뚝딱 개통 $\to$ 품질 체크 $\to$ 쓴 만큼 청구의 꿀 빠는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **공급자 종속 (Vendor Lock-in)**: 아마존(AWS)이나 통신사 NaaS에 길들여졌다가, 나중에 딴 데로 이사 가려니 설정 파일이 호환 안 돼서 독박 쓰는 개빡치는 상황이다.

</details>

| 구분 | **NaaS (서비스형 렌탈망)** | **전통적 온프레미스 (자체 망 구축)** |
|:---|:---|:---|
| 핵심 특징 | 월정액 내고 타는 **쏘카 (렌터카)** | 취등록세 수억 다 내고 산 **내 차 (자가용)** |
| 자산 소유권 | 내가 안 삼. **통신사(사업자) 소유임** | 내 돈 주고 삼. **내 거임 (기업 직접 소유)** |
| 비용 아키텍처 | 쓴 만큼만 쪼개서 내는 **월세 (OpEx)** | 초반에 목돈 수억 꼬라박는 **전세/매매 (CapEx)** |
| 망 개통 속도 | 마우스 클릭 몇 번이면 **당일 5분 개통** | 장비 주문, 배송, 랜선 깔면 **한 달 걸림** |
| 주요 빡침 포인트 | 벤더사에 목줄 잡히면 **이사 가기 빡셈 (Lock-in)** | 장비 낡으면 똥값 되고 **버릴 때도 돈 오지게 듦** |

#### 한줄 요약

- 내 장비(온프레미스)는 비싸고 무거워서 이사 가기 힘들지만, NaaS는 쏘카 빌려 타듯 가벼워서 언제든 확장하고 치고 빠지기 좋다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **종단 간 측정 (End-to-End, E2E)**: 통신사가 "우리 쪽 망은 정상인데요?" 하고 발뺌하는 걸 막으려고, 내 컴퓨터부터 반대편 끝까지 핑을 쏴서 진짜로 안 끊기는지 체크하는 거다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 망 뻗었는데 통신사랑 클라우드가 **서로 "내 잘못 아님" 시전함** | NaaS 망과 클라우드 구간 사이의 책임 경계가 모호해서 폭탄 돌리기 함 | 양 끝단에 **E2E(종단 간) 측정기** 꽂아놓고 실시간으로 패킷 로스 증거 수집 | 장애 구간 명확히 잡고 SLA 위반 위약금 청구 |
| 쓴 만큼 낸다더니 **월말 청구서 보고 뒷목 잡고 쓰러짐** | 디도스 맞거나 트래픽 제어 실패해서 나도 모르게 대역폭을 오지게 땡겨 쓴 거임 | 월간 **트래픽 Cap(한도) 리밋 설정** 빡세게 걸고 게이지 차면 알림 오게 컷트 | 눈먼 요금 폭탄 원천 차단 및 예산 펑크 방지 |
| 다른 통신사로 환승하고 싶은데 **설정이 호환이 안 됨 (종속)** | 특정 사업자의 전용 API와 족보 없는 비표준 모델에 목줄이 묶여 있음 (Lock-in) | 오픈 API 쓰는 곳 고르고, 세팅 값(IaC)을 **JSON/YAML로 내보내기 정기 백업** | 언제든 가방 싸서 환승할 수 있는 주도권 확보 |

#### 한줄 요약

- 통신사 발뺌 막게 E2E로 증거 남기고, 요금 폭탄 발생하기 전에 리밋 걸고, 이사 갈 거 대비해 설정 파일 꼭 빼놔라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 막대한 초기 자본 지출(CapEx)의 끔찍한 부담과 인프라 구축 지연을 박살 내기 위해, **SDN/NFV 가상화 기반** 온디맨드 렌탈망으로 전환하는 NaaS 아키텍처 기조 확립함

#### 한줄 요약

- NaaS는 네트워크를 장비의 족쇄에서 해방시켜, 전기나 수도처럼 틀면 바로 쏟아지는 진정한 '유틸리티'로 진화시켰다.
