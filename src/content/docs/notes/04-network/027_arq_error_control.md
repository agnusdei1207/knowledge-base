## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **자동 재전송 요구(ARQ, Automatic Repeat reQuest)**: 패킷 데이터(프레임) 가다가 분실되거나 찌그러지면, "다시 보내줘!" 하고 송신자 강력히 다시 뜯어내는 강력한 에러 복구 기술이다.

</details>

- 정의: 통신 중 프레임이 유실되거나 훼손됐을 때, 수신자의 응답(ACK/NAK)과 송신자의 타이머를 통해 **자동으로 재전송을 요청하는 2/4계층 오류 제어 기법**
- 배경: 에러가 났는지 단순히 검출(CRC)하는 것만으로는 잃어버린 데이터를 복구할 수 없어, **적극적인 재전송 메커니즘이 필수였기 때문**

#### 한줄 요약

- 에러 나면 버려버리고 끝나는 게 아니라, "몇 번 패킷 안 왔어 다시 줘!" 하고 악착같이 받아내는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ACK(Acknowledgment)**: "여기까지 잘 받았어!" 하고 찍어주는 긍정 확인 도장이다.
- **NAK(Negative Acknowledgment)**: "3번 깨졌잖아 다시 줘!" 하고 깽판 치는 부정 응답이다.
- **순서 번호(Sequence Number)**: 이게 처음 보낸 건지 재전송한 건지 안 헷갈리게 패킷마다 박아둔 바코드다.
- **타임아웃(Timeout)**: "이쯤이면 대답이 올 땐데?" 기다리다 빡쳐서 냅다 다시 쏴버리는 인내심 한계선이다.

</details>

- **순서 번호** 활용 매겨 새 패킷과 재전송 패킷이 섞이는 븅신 같은 중복 상황을 방지함.
- 수신자의 긍정(**ACK**)/부정(**NAK**) 응답과 송신자의 **타임아웃** 재전송의 핵심 트리거로 사용함.
- 한 번에 얼마나 몰아서 쏠지(윈도우 크기)에 따라 ARQ 방식과 대역폭 효율이 완전히 갈림.

#### 한줄 요약

- 대답(ACK) 안 오면 타임아웃 걸려서 다시 쏘고, 깨졌다고(NAK) 징징대도 다시 쏘는 게 ARQ의 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **송신 윈도우(Sender Window)**: 대답 안 들어와도 한 번에 우루루 쏠 수 있는 깡다구(허용량)다.
- **수신 윈도우(Receiver Window)**: 나중에 들어온 놈들 꼬여도 먼저 쌓아둘 수 있는 넉넉한 잉여 버퍼 공간이다.
- **재전송 타이머(Retransmission Timer)**: 패킷 던져놓고 째깍째깍 초재기 들어가는 타이머다.

</details>

```text
[ ARQ 기반 오류 제어 직관적 비교 구조 ]

[ 송신자 ]                                      [ 수신자 ]

[ 1 ][ 2 ][ 3 ] ──( 1번, 2번 정상 / 3번 유실 )──▶ 1번, 2번은 [ 수신 버퍼 ] 적재
   │                                              │
[ 타이머 대기 ] ◀──( 1, 2번 ACK 옴 )───────────────┘
   │
(3번 ACK 안 옴 -> 타임아웃 빡침!)
[ 3번 재전송 ] ─────────────────────────────────▶ 3번 도착 및 복구 완
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **송신 윈도우** | "대답 올 때까지 3개까진 쏜다" 하고 **한 번에 보낼 양 관리** | 송신 버퍼 |
| **수신 윈도우** | 순서 꼬여서 먼저 온 거 **버리지 않고 모아두는 넉넉한 창고** | 수신 버퍼 |
| **순서 번호** | 3번 보냈는데 또 3번 오면 씹으려고 **패킷에 박아둔 바코드** | Seq Number |
| **ACK / NAK** | "잘 왔네(ACK)", "이거 썩었네(NAK)" 하고 **상태 보고서 날림** | 제어 메시지 |
| **재전송 타이머**| 쏜 지 한참 됐는데 대답 없으면 **유실된 줄 알고 다시 쏘는 시한폭탄**| Timeout |

#### 한줄 요약

- 송신 윈도우로 쏘고, 타이머로 초재고, ACK 안 오면 냅다 다시 쏘는 시스템이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **에러 검출(Error Detection)**: 수신자가 패킷 열어보고 체크섬 돌려서 "오염됐네" 하고 판독하는 과정이다.
- **피기배킹(Piggybacking)**: ACK만 덜렁 보내기 아까우니까, 수신자가 데이터 보낼 일 있을 때 ACK를 슬쩍 엎혀서 보내는 꼼수다.

</details>

```text
[ ARQ 재전송 십자포화 알고리즘 흐름 ]

┌──────────────────────────────┐
│ 1. [순서 번호 할당 및 전송]  │
│ (타이머 째깍째깍 시작)       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [수신자 에러 검출]        │
│ (도착한 패킷 썩었나 뜯어봄)  │
└──────────────┬───────────────┘
      ┌────────┴────────┐
(정상: ACK 보냄)  (썩음: NAK / 안옴: 타임아웃)
      │                 │
      ▼                 ▼
┌────────────────┐┌──────────────────────────────┐
│ 3. 윈도우 전진 ││ 4. 해당 패킷 재전송          │
│ (다음 거 쏨)   ││ (송신자 빡쳐서 다시 쏨)      │
└────────────────┘└──────────────────────────────┘
```

### 동작 원리

1. 순서 번호 전송: 바코드(Seq) 찍어서 보내고 동시에 **재전송 타이머** 시작.
2. 수신자 검증: 에러 검출해서 멀쩡하면 ACK 보내고, 썩었으면 냅다 버리고 NAK 보냄.
3. 타임아웃: 송신자는 ACK 안 오면 타임아웃 발생시켜 강제 재전송 때림.
4. 재전송 범위: Go-Back-N인지 SR인지에 따라 한 개만 다시 쏠지 다 쏠지 정함.

#### 한줄 요약

- 에러 나면 NAK 날려서 다시 받고, 중간에 아예 실종되면 타임아웃으로 잡아내서 다시 받는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Stop-and-Wait(정지-대기)**: 하나 보내고 대답 올 때까지 하루 종일 멍때리는 최악의 비효율 방식이다.
- **Go-Back-N(GBN)**: 2번 잃어버렸으면, 뒤에 멀쩡히 도착한 3, 4번까지 싹 다 쓰레기통에 버리고 2번부터 다시 쏘라고 깽판 치는 방식이다. (수신 윈도우=1)
- **Selective Repeat(SR)**: 2번 잃어버리면 3, 4번은 킵해두고 "2번만 다시 줘!" 하는 존나 똑똑한 방식이다. (대신 버퍼 관리 개복잡함)

</details>

| ARQ 방식 | **정지-대기 (Stop-and-Wait)** | **후퇴-N (Go-Back-N)** | **선택 재전송 (Selective Repeat)** |
|:---|:---|:---|:---|
| 작동 방식 | 하나 보내고 ACK 올 때까지 쉼 | 잃어버린 놈 **'부터' 뒤에 싹 다 다시 쏨** | 잃어버린 **'그놈만' 쏙 골라서 다시 쏨** |
| 수신 윈도우 | 1 (버퍼 필요 없음) | 1 (순서 어긋나면 걍 찢어버림) | **N** (어긋난 거 창고에 킵해둠) |
| 장점/단점 | 개간단함 / 개느려터짐 | 버퍼 낭비 없음 / 멀쩡한 놈도 중복 재전송함 | 미친 전송 효율 / 구현 존나 복잡하고 버퍼 낭비 심함 |

#### 한줄 요약

- 정지 대기는 노답, 고백엔(Go-Back-N)은 싹 다 다시 쏘기, 선택 재전송(SR)은 잃어버린 것만 다시 쏘기다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **순방향 오류 정정(FEC, Forward Error Correction)**: 에러 났을 때 "다시 줘(ARQ)" 안 하고, 애초에 보낼 때 힌트(복구 코드)를 같이 넣어서 수신자가 스스로 치료해 버리는 사기 스킬이다 (우주 통신에 씀).
- **RTT(Round-Trip Time)**: 패킷이 갔다 오고 핑 찍히는 시간이다. 이게 너무 들쭉날쭉하면 타임아웃 세팅하기 빡세진다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 멀쩡히 가고 있는데 **송신자가 냅다 중복 재전송함** | 타임아웃이 **RTT**보다 짧게 잡혀서 생긴 조기발루 | RTT 실시간 계산해서 **동적 타임아웃(RTO)** 늘려 잡음 | 대역폭 낭비 및 쓸데없는 패킷 중복 컷 |
| 고속망에서 **Go-Back-N** 썼더니 재전송 늪에 빠져 뻗음 | 한 놈 유실됐는데 뒤에 수백 개를 버리고 다시 쏨 | 고속/오류율 높은 망은 **선택 재전송(SR)** 으로 튜닝 | 쓸데없는 재전송 오버헤드 급격한 저하 |
| 핑 10초 걸리는 위성망에서 **ARQ 썼다가 답답해 뒤짐** | ARQ 재전송 대기 시간(RTT) 극악 | 재전송 없이 알아서 낫는 **FEC(순방향 정정)** 혼합 | 통신 지연시간 획기적 단축 |
| 순서 번호 크기가 너무 작아 **새 패킷을 헌 패킷으로 착각함** | 순서 번호 공간 < 송신 윈도우 크기 | 순서 번호 최댓값을 윈도우 크기의 2배 이상으로 넉넉히 설계 | 신/구 패킷 겹쳐서 생기는 싱크홀 꼬임 방어 |

#### 한줄 요약

- 타임아웃 너무 짧게 잡으면 멀쩡한 것도 다시 쏘니 RTT 잘 재고, 에러 잦은 고속망이면 무조건 SR 써라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **재전송 효율(Retransmission Efficiency)**: 대역폭, 에러율, 버퍼 크기를 짬뽕 계산해서 "이 망에선 SR이 낫다, 저 망에선 GBN이 낫다" 하고 ARQ 방식을 고르는 아키텍트의 저울질이다.

</details>

- **재전송 효율** 극대화를 위해 RTT가 짧고 버퍼가 모자라면 **Go-Back-N** 활용, 고속망에서 유실 복구 효율이 중요하면 **선택 재전송(SR)** 을 도입하고 극단적 지연 망은 **FEC** 활용 혼합하는 하이브리드 기조 확립함

#### 한줄 요약

- 버퍼 아끼려면 Go-Back-N, 대역폭 아끼려면 SR, 아예 다시 보내달라 말하기도 빡세면 FEC를 쓴다.
