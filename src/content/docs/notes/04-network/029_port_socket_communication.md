## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포트(Port)**: 컴퓨터(아파트) 안에서 이게 웹 서버(80동)인지 게임(443동)인지 구별해 주는 상세 주소 번호다.
- **소켓(Socket)**: 애플리케이션(L7)과 네트워크(L4) 사이에서 데이터를 주고받게 해주는 구멍(인터페이스)이다.

</details>

- 정의: **포트** 기반 호스트 내의 특정 프로세스를 식별하고, **소켓** 이 포트를 기반으로 IP와 결합해 통신 상태를 관리하는 **운영체제 종단 객체**
- 배경: IP 주소만으로는 컴퓨터 한 대에 깔린 수많은 앱(카카오톡, 유튜브, 게임) 중 **어디로 데이터를 꽂아줘야 할지 특정할 수 없었기 때문**

#### 한줄 요약

- IP가 건물 주소이고 포트가 부서 번호라면, 소켓은 운영체제가 특정 상대와 대화하도록 구멍을 뚫어놓은 전용 창구다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **고정 포트(Well-known Port)**: 웹(80), 보안웹(443)처럼 전 세계가 약속해서 서버가 문 열어놓고 기다리는 지정 번호(0~1023)다.
- **임시 포트(Ephemeral Port)**: 클라이언트가 서버에 접속할 때 OS가 대충 남는 빈자리 찾아서 꽂아주는 일회용 포트 번호다.
- **5-튜플(5-Tuple)**: "프로토콜, 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트" 이 5가지 정보를 묶어서 하나의 끈끈한 연결로 식별하는 신분증이다.

</details>

- 서버는 널리 알려진 **고정 포트** 활용 열어두고 대기하며, 클라이언트는 운영체제가 할당한 **임시 포트** 활용 사용해 접속함.
- TCP는 리슨 소켓과 연결 소켓을 분리해 1:N 동시 처리를 지원하고, UDP는 소켓 하나로 여러 놈의 데이터를 다 받음.
- **5-튜플** 정보를 기준으로 수만 개의 패킷이 섞이지 않고 정확한 소켓 구멍으로 꽂힘.

#### 한줄 요약

- 클라이언트가 일회용 포트 달고 서버 고정 포트 찌르면, 5-튜플로 신분증 만들어서 전담 마크한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **리슨 소켓(Listen Socket)**: 건물 로비에서 "손님 받습니다~" 하고 안내만 해주는 안내 데스크 전용 소켓이다.
- **연결 소켓(Connected Socket)**: 안내 데스크(리슨 소켓)를 거치면 "1번 손님 이쪽으로" 하고 배정해 주는 1:1 전담 상담 창구다.
- **파일 서술자(FD, File Descriptor)**: 리눅스가 소켓을 파일처럼 다룰 때 부여하는 번호표(ID)다. 이게 꽉 차면 더 이상 연결을 못 받는다.

</details>

```text
[ TCP 소켓 서버 직관적 비교 구조 ]

[ 클라이언트 ]               [ 서 버 ]
(임시 포트)                  (포트 80)

   (접속) ───────────▶ [ 리슨 소켓 (안내 데스크) ]
                              │ (너 1번 방으로 가)
                              ▼
                 ┌────────────────────────┐
                 │ [ 연결 큐 (대기실) ]   │
                 └────────────────────────┘
                              │ (어플이 Accept 하면)
                              ▼
  (통신) ◀──────────▶ [ 연결 소켓 (1번 방) ] (전담 1:1 통신)
  (통신) ◀──────────▶ [ 연결 소켓 (2번 방) ] (전담 1:1 통신)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **클라이언트 소켓**| 운영체제한테 **임시 포트** 받아서 냅다 서버 찌르는 놈 | 출발지 |
| **리슨 소켓** | 80번 포트 열어놓고 **새 손님(SYN)만 쳐다보고 있는 문지기** | 서버 고정 포트 |
| **연결 큐(Backlog)**| 문지기가 인사받은 놈들 **앱이 데려갈 때까지 가둬두는 대기실** | 접속 지연 구간 |
| **연결 소켓** | **5-튜플** 묶어서 이 손님만 1:1로 전담 마크하는 채팅방 | ESTABLISHED |
| **파일 서술자(FD)**| 리눅스가 채팅방마다 달아주는 **주민등록번호(ID)** | 리소스 제한 |

#### 한줄 요약

- 안내 창구(리슨 소켓)가 손님을 받으면, 대기실(연결 큐)에 넣었다가 전용 상담 창구(연결 소켓)를 파서 1:1로 대화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **bind()**: 내 컴퓨터 IP랑 특정 포트 번호를 소켓 구멍에 딱 묶어버리는 세팅 작업이다.
- **listen()**: "자 지금부터 문 엽니다~" 하고 소켓을 수신 대기 상태로 전환하는 선언이다.
- **accept()**: 연결 큐(대기실)에 있는 손님 한 명 데려와서 1:1 전담 마크용 **연결 소켓** 복제해 주는 작업이다.

</details>

```text
[ 소켓 통신 십자포화 생명주기 흐름 ]

┌──────────────────────────────┐
│ 1. [소켓 생성] socket()      │
│ (통신할 빈 파이프 하나 만듦) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [주소 결합] bind()        │
│ (내 IP랑 80번 포트에 꽂음)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [연결 대기] listen()      │
│ (이제 손님 받을 준비 끝남)   │
└──────────────┬───────────────┘
        (클라이언트 접속)
               ▼
┌──────────────────────────────┐
│ 4. [연결 수락] accept()      │
│ (전용 상담 창구 새로 파서 줌)│
└──────────────┬───────────────┘
               ▼
         [ 통신 시작 ]
```

### 동작 원리

1. 주소 결합(bind): 서버 주소와 서비스용 고정 포트를 짝지어 묶는다.
2. 연결 대기(listen): 대기실(백로그) 만들고 외부 접속(SYN)을 받아들일 준비를 마친다.
3. 연결 수락(accept): 대기실에 쌓인 연결 중 하나를 꺼내 전담 마크용 소켓(연결 소켓)을 생성한다.
4. 통신 시작: 클라이언트는 리슨 소켓은 잊어버리고 새로 할당받은 연결 소켓과 1:1로 데이터를 주고받는다.

#### 한줄 요약

- 포트에 묶고(bind), 문 열고 기다리다가(listen), 손님 오면 낚아채서 1:1 방 파준다(accept).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCP 소켓**: 1:1 채팅방처럼 양쪽 상태를 기억하는 깐깐한 소켓이다.
- **UDP 소켓**: 광장 스피커처럼 상대방 안 가리고 막 던지고 다 받는 쿨한 소켓이다.

</details>

| 소켓 방식 | **TCP 소켓 (연결 지향형)** | **UDP 소켓 (데이터그램형)** |
|:---|:---|:---|
| 적용 기준 | 상태 유지와 **1:1 전담 마크** 빡세게 필요할 때 | 빠르고 단순하게 **막 던지고 받을 때** |
| 핵심 특징 | 손님마다 **연결 소켓** 하나씩 새로 파줌 | 소켓 **딱 하나** 기반 만인에게 다 쳐받음 |
| 운영 한계 | 손님 수만큼 파일 서술자(FD) 늘어나서 **서버 메모리/FD 털림** | 누가 누군지 섞인 패킷을 앱 단에서 알아서 똥 닦아야 함 |

#### 한줄 요약

- TCP는 손님마다 전용 방을 파줘서 서버가 털리기 쉽고, UDP는 방 하나에 몰아넣어 앱 개발자가 털리기 쉽다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **백로그(Backlog)**: 애플리케이션(톰캣 등)이 손님(accept)을 너무 늦게 받아가서 대기실에 꽉 찼을 때의 한도치다. 꽉 차면 손님 팅김(Connection Refused).
- **FD 고갈**: OS가 허용해 준 소켓 개수(보통 1024~65535개)를 다 써버려서 더 이상 손님을 못 받는 서버 마비 현상이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 서버 접속 시 **포트가 없다고 에러 뿜음** | 짧은 연결 반복으로 **임시 포트(Ephemeral Port)** 씨가 마름 | 커넥션 풀(Connection Pool) 쓰고, TIME_WAIT 포트 재사용 튜닝 | 신규 접속 불가(포트 고갈) 대참사 해결 |
| 서버 스펙 빵빵한데 접속자가 **자꾸 팅김(Refused)** | 앱 수락(accept) 속도보다 접속이 빨라 **연결 큐(Backlog)** 풀방 됨 | OS 커널 파라미터 및 WAS **백로그 튜닝** 기반 대기실 늘림 | 트래픽 스파이크 시 신규 접속 거부율 떡락 |
| 접속자 많아지니 **"Too many open files" 뿜고 뻗음** | 열린 **연결 소켓(FD)** 이 OS 허용 한도치(ulimit) 초과함 | `ulimit -n` 값 늘리고, 좀비 커넥션 안 생기게 Timeout 칼같이 잡음 | 대규모 1:N 동시 접속(C10K 문제) 처리량 확보 |
| 디비(DB) 포트가 외부에 열려 있어서 털림 | 무방비 포트 노출 | **5-튜플** 식별 기반 방화벽 규칙 적용하여 화이트리스트 IP만 통과 | 서비스 접근 범위 축소 및 보안 통제 획득 |

#### 한줄 요약

- 서버가 뻗으면 남은 포트가 없는지(임시 포트 고갈), 대기실이 꽉 찼는지(백로그 병목), 주민번호가 다 떨어졌는지(FD 고갈) 3가지를 조져라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 상태 기반 1:N 통신은 **TCP 소켓(리슨/연결 분리)** 으로, 고속 단발성 통신은 **UDP 소켓** 기반 처리하되, 대규모 트래픽 시 **임시 포트**, **FD**, **백로그(Backlog)** 튜닝을 통해 병목을 조지는 아키텍처 기조 확립함

#### 한줄 요약

- 소켓 통신은 문 열고(listen) 받는(accept) 단순한 로직이지만, 수만 명이 들이닥칠 때 뻗지 않게 대기실(백로그)과 티켓(FD) 관리를 빡세게 하는 것이 실무의 핵심이다.
