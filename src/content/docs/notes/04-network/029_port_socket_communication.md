## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포트(Port)**: 호스트 내부에서 실행 중인 특정 네트워크 프로세스(애플리케이션)를 식별하기 위해 전송 계층(L4) 헤더에 할당되는 16비트 논리적 식별 번호(0~65535).
- **소켓(Socket)**: 애플리케이션 계층(L7) 프로세스가 운영체제 커널의 네트워크 프로토콜 스택(L4 TCP/UDP)과 통신하기 위해 생성하는 종단점(Endpoint) 추상화 인터페이스 객체.

</details>

- 정의/개념: 호스트 내 실행 중인 프로세스를 식별하는 **포트 번호(16비트)** 와, IP 주소 및 프로토콜과 결합하여 양방향 데이터 통신 세션을 수립하는 **운영체제 소켓(Socket) 인터페이스**
- 배경/필요성: 단일 IP 주소를 공유하는 복수의 애플리케이션 프로세스 간 트래픽 다중화/역다중화(Demultiplexing) 및 프로세스별 통신 세션 제어 요구

#### 한줄 요약
- 16비트 포트 번호로 프로세스를 식별하고, 소켓 인터페이스를 통해 종단 간 통신 세션을 제어한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **잘 알려진 포트(Well-Known Ports)**: IANA가 특정 표준 서비스에 사전에 고정 할당한 0~1023번 범위의 시스템 포트(HTTP 80, HTTPS 443, SSH 22 등).
- **임시 포트(Ephemeral Ports)**: 클라이언트 프로세스가 서버로 아웃바운드 연결 수립 시 운영체제 커널이 동적으로 임시 할당하는 포트(49152~65535 등).
- **5-튜플(5-Tuple)**: 동일 호스트에서 다중 연결을 유일하게 식별하는 5가지 요소인 {프로토콜, 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트}.

</details>

- 포트 범위는 **잘 알려진 포트(0~1023)**, **등록된 포트(1024~49151)**, **동적/사설 포트(49152~65535)** 로 계층적 분류
- 서버는 단일 리슨 포트(80 등)에서 **5-튜플** 식별을 통해 복수의 클라이언트와 독립적인 연결 소켓(Connected Socket)을 1:N 매핑
- 파일 디스크립터(File Descriptor, FD) 기반으로 I/O 인터페이스를 일원화하여 POSIX 표준 소켓 API 지원

#### 한줄 요약
- 포트 분류 체계와 5-튜플 세션 식별을 통해 단일 포트 상에서 1:다 동시 통신을 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **리슨 소켓(Listen Socket)**: 서버 포트에 바인딩되어 클라이언트의 연결 수립 요청(SYN)을 수신 대기하는 관리 전용 소켓.
- **연결 소켓(Connected Socket)**: `accept()` 완료 후 클라이언트와 1:1 데이터 송수신을 전담하기 위해 운영체제 커널이 새로 생성하는 세션 소켓.
- **백로그 큐(Backlog Queue)**: 3-Way Handshake가 진행 중인 SYN 큐(Incomplete)와 핸드셰이크가 완료되어 `accept()` 대기 중인 Accept 큐(Complete)의 버퍼.

</details>

```text
[ 클라이언트 ]                                      [ 서버 호스트 ]
 (임시 포트: 52134)                                   (고정 포트: 80)
 ┌───────────────┐                                   ┌───────────────────────────┐
 │ 클라이언트 소켓│ ─── 1. 연결 요청 (SYN) ─────────▶ │ 리슨 소켓 (Listen Socket) │
 └───────────────┘                                   └─────────────┬─────────────┘
                                                                   │ (연결 큐 적재)
                                                                   ▼
                                                     ┌───────────────────────────┐
                                                     │ 백로그 큐 (SYN/Accept 큐)  │
                                                     └─────────────┬─────────────┘
                                                                   │ accept() 호출
                                                                   ▼
 ┌───────────────┐                                   ┌───────────────────────────┐
 │ 클라이언트 소켓│ ◀── 2. 데이터 송수신 (1:1 세션) ─▶ │ 연결 소켓 (Connected FD) │
 └───────────────┘                                   └───────────────────────────┘
```

선의 의미: 리슨 소켓의 연결 수신부터 백로그 큐 적재 및 accept() 호출을 통한 독립 연결 소켓 생성 구조

| 구성요소 | 책임 | 식별 정보 |
|:---|:---|:---|
| **리슨 소켓 (Listen Socket)** | 서버 포트에 바인딩되어 신규 클라이언트 연결 요청(SYN) 수신 및 큐잉 | 서버 IP + 바인딩 포트 |
| **연결 소켓 (Connected Socket)** | `accept()`를 통해 생성되어 특정 클라이언트와 1:1 실제 데이터 송수신 전담 | **5-튜플 고유 세션** |
| **백로그 큐 (SYN / Accept Queue)** | 애플리케이션이 `accept()`를 호출하기 전까지 완성된 TCP 연결을 보관하는 커널 버퍼 | Backlog 파라미터 |
| **파일 서술자 (FD)** | 운영체제가 소켓 객체를 식별하고 read/write 시스템 콜을 처리하기 위한 인덱스 | 프로세스별 정수 ID |

#### 한줄 요약
- 리슨 소켓, 백로그 큐, 연결 소켓, 파일 서술자(FD)의 협력으로 1:다 다중 클라이언트 통신을 처리한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **POSIX 소켓 시스템 콜 순서**: 서버는 `socket()` $\rightarrow$ `bind()` $\rightarrow$ `listen()` $\rightarrow$ `accept()` $\rightarrow$ `read()`/`write()` $\rightarrow$ `close()` 순으로 호출.

</details>

```text
[ 서버 소켓 수립 ]
1. socket(): TCP 통신용 소켓 엔드포인트 생성 (소켓 FD 획득)
            │
            ▼
2. bind(): IP 주소 및 서비스 포트 번호(예: 80)를 소켓에 바인딩
            │
            ▼
3. listen(): 소켓을 수신 대기 상태로 전환하고 백로그 큐 크기 지정
            │
            ▼ (클라이언트의 connect() 및 3-Way Handshake 완료)
4. accept(): Accept 큐에서 연결을 꺼내 신규 '연결 소켓(Connected Socket)' 반환
            │
            ▼
5. read() / write(): 연결 소켓을 통한 양방향 데이터 스트림 송수신 ➔ 통신 완료 시 close()
```

**동작 원리**

1. **소켓 엔드포인트 생성**: `socket()` 시스템 콜로 커널에 소켓 구조체 및 FD 할당
2. **주소 및 포트 바인딩**: `bind()`로 서버의 로컬 IP와 서비스 포트를 소켓에 결합
3. **수신 대기 모드 진입**: `listen()`으로 소켓 상태를 LISTEN으로 변경하고 커널 연결 큐 생성
4. **연결 수락 및 소켓 분기**: `accept()`로 3-Way Handshake가 끝난 세션에 대해 새로운 연결 소켓 생성
5. **독립 통신 수행**: 리슨 소켓은 계속해서 신규 접속을 받고, 연결 소켓은 클라이언트와 통신 처리

#### 한줄 요약
- socket, bind, listen, accept 순서로 연결을 수립하고, 리슨 소켓과 연결 소켓을 분리하여 처리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **블로킹 소켓(Blocking Socket)**: I/O 작업(read/write/accept)이 완료될 때까지 호출 스레드가 대기 상태로 정지되는 방식.
- **논블로킹/이벤트 기반 소켓(Non-blocking / Event-driven)**: I/O 준비 완료 여부를 `epoll`/`kqueue` 등의 멀티플렉서로 감시하여 단일 스레드로 수만 개의 소켓을 처리하는 방식.

</details>

| 비교 항목 | TCP 소켓 (Stream Socket) | UDP 소켓 (Datagram Socket) |
|:---|:---|:---|
| **소켓 유형** | `SOCK_STREAM` (연결 지향) | `SOCK_DGRAM` (비연결형) |
| **서버 동작 구조** | 리슨 소켓과 **연결 소켓의 분리 운용 (1:N)** | **단일 소켓**으로 다수 클라이언트 송수신 |
| **연결 수립 절차** | `listen()`, `accept()`, `connect()` 필수 | 사전 연결 절차 없이 `sendto()`, `recvfrom()` 수행 |
| **운영체제 자원 소모** | 연결마다 세션 상태 및 독립 FD 점유 | 단일 소켓 FD 유지로 커널 메모리 소모 극소화 |

#### 한줄 요약
- TCP 소켓은 연결별 전담 소켓을 분리 생성하고, UDP 소켓은 단일 엔드포인트로 메시지를 송수신한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **epoll(이벤트 기반 I/O 멀티플렉싱)**: 수만 개의 소켓 파일 디스크립터(FD) 중 실제 이벤트가 발생한 소켓만 O(1) 복잡도로 추출하는 고성능 리눅스 시스템 콜(C10K 문제 해결).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단기간 대규모 아웃바운드 세션 생성 시 **임시 포트(Ephemeral Port) 고갈** | HTTP Keep-Alive 커넥션 풀링 및 `ip_local_port_range` 범위 확장 | 임시 포트 고갈 방지 및 세션 수립 지연 해소 |
| 트래픽 급증 시 신규 연결 요청 거부(**Connection Refused / SYN Drop**) | 커널 `tcp_max_syn_backlog` 및 `somaxconn` **백로그 큐 확장** | SYN 스파이크 흡수 및 연결 수락 대기열 안정화 |
| 동시 접속자 증가 시 **"Too many open files" 에러 및 프로세스 중단** | 운영체제 **`ulimit -n` 최대 파일 디스크립터(FD) 한도 증설** | 대규모 1:다 동시 연결(C10K/C1000K) 수용량 확보 |

#### 한줄 요약
- 커넥션 풀링으로 임시 포트를 보호하고, 백로그 큐를 확장하며, ulimit 설정을 통해 FD 고갈을 방지한다.

## Ⅶ. 결론

- 대규모 동시 접속을 처리하는 고성능 서버 아키텍처 구축 시 **포트 번호**와 **소켓 생명주기**의 동작 원리를 고려하여, **epoll/kqueue 기반 논블로킹 I/O**를 적용하고 커널의 **백로그 큐(somaxconn)** 와 **FD 한도(ulimit)** 를 정밀 튜닝하여 시스템 처리량을 극대화

#### 한줄 요약
- 논블로킹 I/O 멀티플렉싱과 커널 파라미터 최적화를 통해 고성능 소켓 서버 인프라를 완성한다.
