## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **UDP (User Datagram Protocol)**: 전송 계층(L4)에서 연결 수립 및 상태 관리 없이 8바이트 고정 헤더로 데이터그램을 즉시 송출하는 비연결형 프로토콜 (RFC 768).
- **Datagram (데이터그램)**: 이전이나 이후의 패킷과 연결 상태를 공유하지 않고 독립적으로 라우팅되는 PDU 전송 단위.

</details>

- 정의/개념: 사전 연결 설정 없이 **8바이트 고정 헤더와 메시지 경계 보존을 통해 초저지연 데이터그램을 송수신하는 L4 비연결형 전송 프로토콜**
- 배경/필요성: TCP의 3-Way Handshake 및 재전송 메커니즘으로 인한 **실시간 음성/영상 버퍼링 지연(Jitter), 단일 패킷 유실 시 전체 세션 블로킹 한계 해결 불가**

#### 한줄 요약
- 사전 연결 설정 없이 8바이트 헤더로 메시지 경계를 보존하며 초저지연 전송을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Message Boundary (메시지 경계)**: 송신 측의 단일 `send()` 크기 그대로 수신 측의 `recv()`로 1:1 보존되는 특성 (TCP 스트림과 대비).
- **Pseudo Header (의사 헤더)**: UDP 체크섬 계산 시 IP 스푸핑 및 오라우팅을 방지하기 위해 출발지/목적지 IP와 프로토콜 번호를 가상 결합하는 12B 헤더.

</details>

- 사전 핸드셰이크 없이 즉시 패킷을 송출하는 **비연결성(Connectionless) 및 초저지연**
- 응용 계층이 전달한 패킷의 크기를 그대로 유지하는 **메시지 경계(Message Boundary) 보존**
- 1:1 유니캐스트뿐 아니라 **1:N 멀티캐스트 및 1:전체 브로드캐스트 전송 완벽 지원**

#### 한줄 요약
- 비연결성, 8바이트 고정 헤더, 메시지 경계 보존, 멀티캐스트/브로드캐스트 지원을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **UDP 8바이트 고정 헤더**: Source Port(2B), Destination Port(2B), Length(2B), Checksum(2B).

</details>

```text
[UDP 데이터그램 8바이트 고정 헤더 및 페이로드 구조]
|-- L4 Header (8 Bytes 고정)
|   |-- Source Port (16-bit, 2 Bytes: 송신 프로세스 식별)
|   |-- Destination Port (16-bit, 2 Bytes: 수신 프로세스 식별, 예: DNS 53, DHCP 67)
|   |-- Length (16-bit, 2 Bytes: 헤더 + 페이로드 전체 바이트 길이, 최소 8B)
|   `-- Checksum (16-bit, 2 Bytes: 의사헤더 + UDP헤더 + 데이터 오류 검출)
`-- Application Payload (가변 크기 데이터)
```

선의 의미: 계층 및 16비트 포트 번호 2개, 길이, 체크섬으로 구성된 8바이트 헤더 뒤에 응용 데이터가 캡슐화되는 구조

| 필드명 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **출발지 포트 (Source)** | 송신 프로세스 식별 번호로 **응답이 불필요한 단방향 전송 시 0으로 설정 가능** | 16비트 (2 Bytes) |
| **목적지 포트 (Destination)**| 수신 호스트 내에서 패킷을 수신할 **응용 서비스 식별 (DNS 53, DHCP 67, QUIC 443)** | 16비트 (2 Bytes) |
| **전체 길이 (Length)** | UDP 헤더(8B)와 페이로드를 합산한 **데이터그램 전체의 바이트 크기 (최소 8바이트)** | 16비트 (2 Bytes) |
| **체크섬 (Checksum)** | IP 의사 헤더와 헤더, 데이터를 포함한 **비트 오류 검출 (IPv4 선택, IPv6 필수)** | 16비트 (2 Bytes) |

#### 한줄 요약
- 출발지 포트, 목적지 포트, 전체 길이, 체크섬 4개 필드(8바이트)로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **UDP 무상태 전송 4단계**: 소켓 생성 및 `sendto()` $\to$ 8바이트 헤더 캡슐화 $\to$ IP 비연결 포워딩 $\to$ 수신단 체크섬 검증 및 `recvfrom()` 인계.

</details>

```text
UDP 데이터그램 송수신 파이프라인
        │
   1. [송신 소켓 호출] 응용 프로세스가 `sendto()` 시스템 콜 호출 (메시지 경계 보존)
        │
   2. [8바이트 헤더 조립] 출발지/목적지 포트 및 길이 기록 후 의사헤더 기반 체크섬 산출
        │
   3. [비연결 IP 송출] 연결 핸드셰이크 없이 즉시 인터넷 IP 계층으로 패킷 발사
        │
   4. [수신단 체크섬 검증] 수신 NIC가 체크섬 계산
   ┌────┴───────────────────────────┐
  체크섬 정상 (무결성 확인)        체크섬 불일치 (비트 에러)
   │                                 │
5A. [수신 소켓 인계]                5B. [패킷 즉시 폐기 (Drop)]
   `recvfrom()`으로 응용 큐에 1:1 전달   오류 알림 없이 Silent Drop
```

#### 한줄 요약
- 소켓 호출 → 8바이트 캡슐화 → 비연결 IP 송출 → 체크섬 검증 → 응용 소켓 인계 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **UDP vs TCP**: 비연결 데이터그램 초저지연 전송(UDP)과 연결형 바이트 스트림 신뢰성 전송(TCP).

</details>

| 비교 항목 | 사용자 데이터그램 프로토콜 (UDP) | 전송 제어 프로토콜 (TCP) |
|:---|:---|:---|
| **연결 지향성** | **비연결형 (Connectionless, No Handshake)** | **연결 지향형 (3-Way Handshake 수립)** |
| **전송 단위 및 경계** | **데이터그램 (메시지 경계 보존)** | **바이트 스트림 (경계 없음, 분할/합성)** |
| **헤더 오버헤드** | **8 바이트 고정** | 20 ~ 60 바이트 가변 |
| **신뢰성 보장** | **미보장 (패킷 유실/순서 역전 허용)** | **보장 (시퀀스 번호, ACK, 타임아웃 재전송)** |
| **흐름 및 혼잡 제어** | **미지원 (네트워크 대역폭 무관 송출)** | **지원 (Sliding Window, AIMD 혼잡 제어)** |
| **주요 대표 서비스** | **DNS, DHCP, SNMP, WebRTC, QUIC (HTTP/3)**| **HTTP/1.1, HTTP/2, HTTPS, FTP, SSH, DB** |

#### 한줄 요약
- UDP는 비연결 데이터그램 초저지연을 제공하고, TCP는 연결형 바이트 스트림 신뢰성을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **UDP Amplification DDoS**: 공격자가 출발지 IP를 피해자 IP로 스푸핑하여 공개 DNS/NTP/SNMP 서버에 쿼리를 보내 수십~수백 배 커진 응답 트래픽을 피해자로 집중시키는 반사 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 출발지 IP 위조를 통한 UDP 반사 증폭 디도스(DNS/NTP) 공격 | **개방형 리졸버 차단, `RRL(Response Rate Limiting)` 및 BCP 38 적용** | 증폭 반사 트래픽 차단 및 가용성 수호 |
| 대용량 UDP 전송 시 IP 단편화 발생 및 단일 조각 유실 시 전체 폐기 | **응용 계층 페이로드 크기를 `Path MTU(통상 1,472B 이하)`로 제한** | IP 단편화 원천 방지 및 전송 성공률 향상 |
| 패킷 유실 및 지터(Jitter)로 인한 실시간 영상/음성 품질 저하 | **응용 계층에 `FEC(전방 오류 정정)` 및 `지터 버퍼(Jitter Buffer)` 구현** | 재전송 대기 없는 자체 복원 및 연속 재생 |
| UDP 패킷 무단 폭주로 인한 백본 네트워크 대역폭 고갈 | **애플리케이션 계층 `토큰 버킷(Token Bucket) 레이트 리미팅` 강제** | 공정 대역폭 공유 및 네트워크 붕괴 방어 |

#### 한줄 요약
- RRL/BCP 38 보안, Path MTU 제한, FEC 지터 버퍼링, 토큰 버킷 레이트 리미팅으로 운영한다.

## Ⅶ. 결론

- 실시간성과 초고속 전송이 요구되는 차세대 네트워크를 구현하기 위해 **UDP의 경량 8바이트 헤더와 비연결성 특성을 활용**하고, 신뢰성과 보안이 요구되는 웹 환경에서는 UDP 기반 위에 TLS 1.3 암호화와 멀티플렉싱 및 패킷 복원을 사용자 공간에 결합한 **QUIC(HTTP/3)** 표준을 전면 도입하여 무지연 고신뢰 통신 인프라 완성

#### 한줄 요약
- UDP는 8바이트 최소 헤더와 메시지 경계 보존을 통해 초저지연을 실현하며, QUIC과 FEC를 결합하여 차세대 인터넷을 주도하는 핵심 전송 프로토콜이다.
