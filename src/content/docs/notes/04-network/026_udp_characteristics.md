## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **사용자 데이터그램 프로토콜(User Datagram Protocol, UDP)**: 전송 계층(L4)에서 사전에 연결을 수립하지 않고, 최소한의 제어 정보(8바이트 헤더)만을 부착하여 독립적인 데이터그램 단위로 데이터를 고속 전송하는 비연결형 프로토콜 (RFC 768).
- **데이터그램(Datagram)**: 각 패킷이 상호 독립적으로 라우팅되며, 이전이나 이후의 패킷과 연결 상태를 공유하지 않는 전송 단위.

</details>

- 정의/개념: 연결 수립(Handshake) 및 흐름/혼잡 제어 오버헤드를 배제하고, **8바이트 최소 헤더** 와 **메시지 경계 보존** 특성을 통해 실시간 전송 지연을 최소화한 **비연결형 전송 프로토콜(UDP)**
- 배경/필요성: 실시간 음성/영상 스트리밍(VoIP, WebRTC) 및 질의-응답(DNS, DHCP) 서비스에서 TCP의 3-Way Handshake 지연과 재전송에 의한 지연 변동(Jitter)을 회피할 요구

#### 한줄 요약
- 사전 연결 설정 없이 8바이트 헤더로 메시지 경계를 보존하며 초저지연 데이터그램을 전송한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비연결성(Connectionless)**: 송수신 호스트 간에 논리적 연결 상태(State)를 수립하거나 유지하지 않고 즉시 데이터를 송출하는 속성.
- **메시지 경계 보존(Message Boundary)**: TCP의 바이트 스트림(Byte Stream)과 달리, 송신 응용 계층이 기록한 1회의 `write()` 데이터 크기가 수신단에서 동일한 1회의 `read()` 크기로 정확히 일치하여 수신되는 특성.
- **체크섬(Checksum)**: 전송 중 발생한 비트 반전 오류만을 검출하여 손상된 데이터그램을 폐기하며, 재전송이나 순서 재조립은 수행하지 않는 최소 무결성 검증 필드.

</details>

- **사전 핸드셰이크 지연 0ms**: 연결 설정 절차 없이 즉시 데이터 전송을 개시하여 초기 지연 시간(TTFB) 최소화
- **최소 제어 오버헤드 (8바이트 고정 헤더)**: TCP(20~60바이트) 대비 헤더 오버헤드가 극소화되어 네트워크 대역폭 효율 극대화
- **신뢰성 제어의 상위 계층 위임**: 패킷 손실, 순서 역전, 흐름/혼잡 제어가 필요한 경우 응용 계층(L7 / QUIC)에서 선택적 구현

#### 한줄 요약
- 비연결성, 8바이트 고정 헤더, 메시지 경계 보존 및 선택적 응용 계층 신뢰성 제어를 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **의사 헤더(Pseudo Header)**: UDP 체크섬 계산 시 IP 스푸핑 및 오라우팅을 방지하기 위해 출발지 IP, 목적지 IP, 프로토콜 번호(17), UDP 길이를 포함하는 12바이트 가상 헤더 구조.

</details>

```text
[ UDP 데이터그램 헤더 구조 (총 8바이트) ]

 0                   15 16                  31 비트
┌──────────────────────┬──────────────────────┐
│  Source Port (2B)    │ Destination Port (2B)│
├──────────────────────┼──────────────────────┤
│    Length (2B)       │    Checksum (2B)     │
├──────────────────────┴──────────────────────┤
│               Application Data               │
│                   (Payload)                  │
└──────────────────────────────────────────────┘
```

선의 의미: 16비트 포트 번호 2개, 16비트 전체 길이, 16비트 체크섬으로 구성된 8바이트 고정 헤더와 가변 길이 페이로드

| 필드명 | 바이트 크기 | 책임 및 역할 |
|:---|:---|:---|
| **출발지 포트 (Source Port)** | 2 Bytes (16 bits) | 송신 프로세스를 식별하며, 응답이 불필요한 경우 0으로 설정 가능 |
| **목적지 포트 (Destination Port)** | 2 Bytes (16 bits) | 수신 호스트 내에서 패킷을 수신할 응용 계층 서비스 식별 (DNS 53, DHCP 67) |
| **전체 길이 (Length)** | 2 Bytes (16 bits) | UDP 헤더와 페이로드를 합산한 전체 데이터그램의 바이트 길이 (최소 8바이트) |
| **체크섬 (Checksum)** | 2 Bytes (16 bits) | IP 의사 헤더, UDP 헤더, 데이터를 포함한 전송 중 비트 오류 검출 (IPv6 필수) |

#### 한줄 요약
- 출발지 포트, 목적지 포트, 전체 길이, 체크섬의 4개 필드(8바이트)로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터그램 전송 파이프라인**: 응용 계층의 버퍼가 소켓을 통해 단일 시스템 콜로 IP 계층에 전달되고 수신 측 소켓 큐로 즉시 인계되는 무상태 전송 절차.

</details>

```text
[ 송신 응용 (DNS / VoIP / QUIC) ] ──▶ `sendto()` 시스템 콜 호출
                                            │ (메시지 경계 보존)
                                            ▼
[ UDP 계층 ] ───────────────────────▶ 8바이트 UDP 헤더 부착 및 체크섬 계산
                                            │
                                            ▼
[ IP 네트워크 계층 ] ───────────────▶ 비연결형 IP 패킷 캡슐화 및 최선형 라우팅 송출
                                            │
                                            ▼ (인터넷 전송)
[ 수신 호스트 UDP 계층 ] ───────────▶ 체크섬 유효성 검증 (오류 발생 시 패킷 즉시 폐기)
                                            │ (정상 패킷)
                                            ▼
[ 수신 응용 소켓 버퍼 ] ────────────▶ `recvfrom()` 시스템 콜로 원본 메시지 1:1 수신
```

**동작 원리**

1. **데이터그램 생성**: 응용 프로세스가 메시지를 생성하여 UDP 소켓으로 전송
2. **헤더 캡슐화**: 출발지/목적지 포트와 길이를 기록하고 의사 헤더 기반 체크섬 산출
3. **무상태 전송**: 연결 수립 없이 IP 계층을 통해 목적지 호스트로 패킷 즉시 발송
4. **무결성 검사 및 인계**: 수신단 UDP가 체크섬을 검증하여 에러가 없을 경우 해당 포트의 수신 큐로 즉시 전달

#### 한줄 요약
- 소켓 호출, 8바이트 헤더 캡슐화, 무상태 IP 전송, 수신단 체크섬 검증 및 응용 큐 인계 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **바이트 스트림(Byte Stream)**: 데이터의 시작과 끝 경계가 구분되지 않고 연속된 바이트의 흐름으로 전달되는 TCP의 전송 방식.

</details>

| 비교 항목 | 사용자 데이터그램 프로토콜 (UDP) | 전송 제어 프로토콜 (TCP) |
|:---|:---|:---|
| **연결 지향성** | **비연결형 (Connectionless, No Handshake)** | 연결 지향형 (3-Way Handshake 수립) |
| **전송 단위 및 경계** | **데이터그램 (메시지 경계 보존)** | **바이트 스트림 (경계 없음, 분할/합성)** |
| **헤더 크기** | **8 바이트 고정** | 20 ~ 60 바이트 가변 |
| **신뢰성 보장** | 미보장 (패킷 유실/순서 역전 허용) | **보장 (시퀀스 번호, ACK, 타임아웃 재전송)** |
| **흐름/혼잡 제어** | 미지원 (네트워크 용량 무관 송출) | **지원 (Sliding Window, AIMD, Slow Start)** |
| **주요 활용 서비스** | **DNS, DHCP, SNMP, 실시간 VoIP, QUIC(HTTP/3)** | **HTTP/1.1, HTTP/2, HTTPS, FTP, SSH, DB 연동** |

#### 한줄 요약
- UDP는 비연결형 데이터그램 초저지연 전송을 제공하고, TCP는 연결형 바이트 스트림 신뢰성 전송을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **UDP 반사·증폭 디도스(UDP Amplification DDoS)**: 공격자가 출발지 IP를 피해자 IP로 위조(Spoofing)하여 공개 DNS/NTP/SNMP 서버로 요청을 보내고, 수십~수백 배 커진 응답 트래픽이 피해자 서버로 집중되도록 유발하는 공격.
- **경로 MTU 초과 단편화(IP Fragmentation)**: 대형 UDP 패킷이 중간 라우터의 MTU보다 클 때 IP 단편화가 발생하며, 조각 중 하나라도 유실되면 전체 데이터그램이 폐기되는 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비연결 특성 악용 출발지 IP 위조 기반 **UDP 증폭 DDoS(DNS/NTP)** 공격 | 개방형 리졸버 차단, **RRL(Response Rate Limiting)** 및 소스 검증(BCP 38) | 반사 공격 트래픽 차단 및 표적 시스템 가용성 보호 |
| 대용량 UDP 전송 시 IP 단편화(Fragmentation) 발생 및 단일 조각 유실 시 전체 폐기 | 응용 계층 페이로드 크기를 **Path MTU(통상 1,472B 이하)** 로 제한 | IP 단편화 원천 방지 및 전송 성공률 향상 |
| 패킷 유실 및 지터(Jitter)로 인한 실시간 미디어 음질/화질 저하 | 응용 계층에 **전방 오류 정정(FEC)** 및 **지터 버퍼(Jitter Buffer)** 구현 | 재전송 대기 없는 패킷 자체 복원 및 재생 연속성 보장 |

#### 한줄 요약
- RRL/BCP 38로 증폭 DDoS를 차단하고, MTU 이하 패킷화로 단편화를 방지하며, FEC로 실시간 복원력을 확보한다.

## Ⅶ. 결론

- 실시간성 및 고속 전송이 요구되는 인프라는 **UDP** 를 기본 전송 계층으로 채택하되, 신뢰성과 보안이 요구되는 최신 웹 및 미디어 환경에서는 UDP 위에서 암호화(TLS 1.3), 패킷 복원, 혼잡 제어를 사용자 레벨로 구현한 **QUIC (HTTP/3)** 표준 프로토콜을 도입하여 지연 최소화와 전송 신뢰성을 동시에 확보

#### 한줄 요약
- 초저지연 UDP 기반에 QUIC 신뢰성 제어를 융합하여 차세대 인터넷 전송 인프라를 완성한다.
