## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **UDP(User Datagram Protocol)**: "잘 받았어?" 같은 확인 절차(3-Way Handshake) 싹 다 씹고, 일단 냅다 데이터부터 꽂아 넣고 보는 쿨한 폭주족 프로토콜이다.

</details>

- 정의: TCP와 달리 연결 설정 과정(Handshake) 없이 메시지 경계를 보존한 데이터그램을 냅다 던지는 **비연결형 전송 프로토콜**
- 배경: 실시간 게임이나 음성 통화(VoIP)처럼, 중간에 패킷 하나 잃어버리더라도 **재전송 기다리는(지연) 것보다 무조건 빨리 쏘는 게 더 중요했기 때문** #### 한줄 요약

- 대답 안 기다리고 일단 봉투 째로 냅다 던진 다음, 수신자 생사 여부는 1도 신경 안 쓰는 초고속 프로토콜이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비연결형(Connectionless)**: 상대방이 죽었든 살았든, 바쁘든 말든 묻지도 따지지도 않고(No State), 걍 주소만 찍고 우편물 집어 던지는 쿨한 성질이다.
- **체크섬(Checksum)**: UDP가 하는 유일한 품질 검사로, 배달 중에 패킷이 찌그러졌는지(비트 오류) 확인만 하고 찌그러졌으면 걍 쓰레기통에 버리는 최소한의 양심이다.

</details>

- **비연결형** 특성으로 3-Way Handshake 같은 귀찮은 사전 작업 없이 0초 만에 냅다 전송 시작함.
- TCP처럼 데이터를 짬뽕시키지 않고 응용 메시지의 원본 경계(데이터그램 단위)를 봉투째 그대로 보존함.
- **체크섬** 기반 비트 깨진 것만 걸러내고, 순서나 패킷 로스 복구는 **애플리케이션(L7) 니가 알아서 하라고 짬 때림**.

#### 한줄 요약

- TCP의 깐깐한 절차(연결, 순서, 재전송)를 다 갖다 버린 덕분에 미친 속도를 낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **데이터그램(Datagram)**: UDP가 던지는 하나의 편지 봉투로, 짬뽕되거나 쪼개지지 않고 독립적으로 논다.
- **페이로드(Payload)**: 봉투 안에 든 진짜 애플리케이션 데이터(유튜브 영상, 롤 좌표 등) 짐칸이다.

</details>

```text
[ 직관적 비교 기반 UDP 헤더(딱 8바이트) 구조 ]

[ 출발지 포트 (2B) ]  [ 목적지 포트 (2B) ]
[   전체 길이 (2B) ]  [   체크 섬   (2B) ]
───────────────────────────────────────
[            데이터 (페이로드)           ]
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **출발지 포트** | "답장할 거면 여기로 해" (근데 안 적어도 됨) | 16비트 |
| **목적지 포트** | 트래픽 꽂아넣을 타겟 앱(게임, 카톡 등) | 16비트 |
| **길이** | 헤더 + 페이로드 합친 전체 패킷 데이터 사이즈 | 최대 65,535B |
| **체크섬** | 배달 중 훼손됐나? $\to$ **찌그러지면 걍 버림** | 에러 '검출'만 |
| **페이로드** | 응용 계층이 쑤셔 넣은 원본 짐칸 내용물 | 메시지 경계 |

#### 한줄 요약

- TCP 헤더가 덕지덕지 20바이트일 때, UDP 헤더는 딱 필요한 4개(8바이트)만 들고 뛰어서 가볍고 빠르다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IP(Internet Protocol)**: "야, 수신자 IP 주소로 가라" 하고 L3(라우터)한테 배달 위탁 인터페이스 주는 하부 프로토콜이다.
- **데이터그램 검증(Datagram Validation)**: 수신자가 봉투(UDP) 열기 전에 체크섬 확인해서 "이거 썩었네" 하고 가차 없이 쓰레기통에 쳐박는 과정이다.

</details>

```text
[ UDP 무지성 십자포화 송수신 흐름 ]

[ 송신 응용 (게임/VoIP) ]
           │ (데이터 줄게 쏴라)
           ▼
┌──────────────────────────────┐
│ 1. [데이터그램 생성]         │
│ (포트 띡 붙이고, 체크섬 박음)│
└──────────────┬───────────────┘
               ▼ (무조건 IP로 던짐)
       [ 인터넷 (IP 망) ]
               ▼ (수신 측 도착)
┌──────────────────────────────┐
│ 2. [데이터그램 검증]         │
│ (체크섬 까보기)              │
└──────────────┬───────────────┘
               ├── (에러) ──▶ (쓰레기통에 폐기)
               ▼ (정상)
    [ 목적지 응용 프로그램 ] (카톡, 게임 등)
```

### 동작 원리

1. 데이터그램 생성: 포트 번호랑 훼손 검사용 **체크섬** 한정 띡 붙여서 **IP** 망으로 냅다 던짐.
2. 데이터그램 검증: 수신 측 UDP가 체크섬 까보고, 찌그러진 건 버리고 멀쩡한 것만 앱으로 올려줌.

#### 한줄 요약

- 쏠 땐 대충 봉투에 담아 막 던지고, 받을 땐 봉투 찢어진 것만 버리고 위로 올려보내는 초간단 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TCP(Transmission Control Protocol)**: "느려도 무조건 확실하게!" 분실물 생기면 강력히 다시 받아내는 깐깐한 모범생 배달부다.

</details>

| 전송 방식 | **UDP (폭주족)** | **TCP (모범생)** |
|:---|:---|:---|
| 적용 기준 | 잃어버려도 되니까 **무조건 빨라야 함 (지연 극혐)** | 늦어도 되니까 **한 글자도 안 틀려야 함 (손실 극혐)** |
| 핵심 특징 | 연결 안 맺고 **데이터그램** 무지성 투척 | 3-Way로 연결 맺고 깐깐하게 **바이트 스트림** 쏨 |
| 단점/한계 | 손실/순서 꼬이면 앱 개발자가 직접 똥 닦아야 함 | 3-Way 딜레이 길고 1번 패킷 날아가면 전체 올스톱 |

#### 한줄 요약

- 속도 무새(실시간, DNS)는 UDP를 쓰고, 꼼꼼 무새(웹, 파일 전송)는 TCP를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **반사 공격(Reflection) / 증폭 공격(Amplification)**: UDP가 "나 누구게?" 하고 신분 속이기(위조) 쉬운 점을 악용해, 타겟(피해자) IP로 신분 세탁한 뒤 DNS에 요청을 던져 100배 큰 융단폭격(DDoS) 응답이 피해자한테 꽂히게 만드는 씹악질 공격이다.
- **MTU(Maximum Transmission Unit)**: 패킷 데이터차가 싣고 갈 수 있는 최대 박스 크기(보통 1500바이트). UDP가 이거보다 크게 보내면 멍청한 IP가 냅다 쪼개버린다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 패킷 날아갔는데 **UDP라 재전송(복구)을 안 해줌** | UDP 자체엔 재전송 로직 전무함 | 어플리케이션(L7) 단에서 **재시도 및 중복 제거** 로직 직접 짬 | TCP보단 가벼운 맞춤형 신뢰성 획득 |
| 해커가 출발지 IP 위조해서 **UDP 증폭(DDoS) 공격 때림** | UDP는 3-Way 안 해서 출발지 속이기 개쉬움 (Spoofing) | DNS/NTP 서버 응답 크기 제한 및 **쿠키(Cookie) 검증** 튜닝 | 무고한 피해자 서버 발생하는 대규모 네트워크 장애 방어 |
| 덩치 엄청 큰 UDP 보냈더니 **중간 라우터에서 다 깨짐** | 패킷이 경로 **MTU** 활용 초과해 무식하게 쪼개짐 (IP 단편화) | 앱 단에서 애초에 보낼 때 **경로 MTU(1500B)** 이하로 쪼개서 던짐 | 단편화된 조각 하나 날아가서 전체 패킷 버려지는 참사 방지 |

#### 한줄 요약

- UDP 쓰려면 앱 개발자가 패킷 꼬이는 거 직접 케어해야 하고, 증폭 공격(DDoS) 안 맞게 방어벽 쳐야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **응용 재시도(Application Retry)**: 멍청한 UDP를 믿지 않고 앱 단위(예: QUIC)에서 시퀀스 번호 매겨서 "2번 패킷 안 왔네 다시 줘" 하고 직접 챙기는 기능이다.
- **IP 단편화(IP Fragmentation)**: UDP 패킷이 너무 커서 잘게 쪼개진 상태. 이 중 하나라도 유실되면 조립(Reassembly) 못해서 전체 패킷을 다 찢어 버려야 하는 헬게이트다.

</details>

- 지연에 민감한 실시간 스트리밍은 **UDP** 기반 신속 처리하고, 신뢰성이 필요하면 L7에서 **응용 재시도** 활용 구현하며 **IP 단편화** 기반 인한 헬게이트를 피하는 튜닝 기조 확립함

#### 한줄 요약

- UDP는 네트워크 지연을 극도로 줄이는 대신, 잃어버린 데이터에 대한 책임(재전송)을 응용 프로그램에 넘기는 등가교환이다.
