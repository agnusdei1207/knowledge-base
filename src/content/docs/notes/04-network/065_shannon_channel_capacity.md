## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **채널 용량 (Channel Capacity)**: 주어진 주파수(고속도로 폭)와 전파 상태(신호대잡음비)에서 데이터가 안 깨지고 통과할 수 있는 이론적 절대 최고 속도(Max bps)다.
- **섀넌 한계 (Shannon Limit)**: 정보이론의 1타 강사 섀넌 할아버지가 수식으로 증명한 "물리적으로 이 속도 이상은 절대 못 낸다"는 통신계의 얄짤 없는 절대 뚜껑(법칙)이다.

</details>

- 정의: **채널 용량** 특정 대역폭과 신호대잡음비(SNR) 조건에서 오류 없이 쏠 수 있는 데이터 전송률의 이론적 한계점(섀넌 한계)을 의미한다.
- 배경: 통신사들이 5G 속도 100Gbps 낼 수 있다고 입 털며 약 파는 걸 막고, **물리적으로 가능한 진짜 한계선이 어딘지 수학적으로 못 박기 위해 제정되었다.**

#### 한줄 요약

- 주파수 대역폭과 잡음을 계산해서 "이 환경에선 1Gbps 이상 절대 안 나옴!" 하고 물리적 속도 뚜껑을 덮어버리는 공식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **대역폭 (Bandwidth)**: 통신사가 정부한테 수조 원 주고 산 주파수 덩어리 크기다. 대역폭을 두 배로 늘리면 속도도 쿨하게 정비례로 두 배 늘어난다.
- **신호대잡음비 (SNR)**: 쓰레기 잡음(N) 대비 진짜 내 신호(S)가 얼마나 센지를 나타낸다. 이건 아무리 빡세게 올려도 로그(Log) 함수의 통곡의 벽에 막혀서 속도가 찔끔찔끔 늘어난다.

</details>

- **대역폭의 선형 마법 (B)**: 고속도로 차선을 2차선에서 4차선으로 늘리면 차가 뻥뻥 뚫리듯이, 대역폭(Hz)을 두 배 늘리면 전송 용량도 정직하게 두 배로 떡상한다.
- **SNR의 로그 통곡의 벽 (Log)**: 기지국 출력을 급격히 빵빵하게 쏴서 신호를 키워봤자, 로그 함수 특성 때문에 용량은 찔끔 오르다 멈춰버리는 가성비 똥망 현상에 부딪힌다.
- **에러율 0% 보장**: 섀넌 한계선 속도 밑으로만 조절해서 쏘면, 수학적으로 데이터가 절대 안 깨지는(에러율 0%) 무적 전송이 가능하다.

#### 한줄 요약

- 속도 올리고 싶으면 파워(SNR) 백날 키워봐야 로그벽에 막히니까, 비싸더라도 주파수 폭(대역폭) 자체를 늘려야 한다는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **수식 기호 (Formula Notation)**: $C = B \log_2 (1 + S/N)$ 수식에서 $C$는 용량(bps), $B$는 대역폭(Hz), $S/N$은 잡음 대비 신호 파워의 선형비를 뜻하는 절대 방정식이다.

</details>

```text
[ 섀넌의 절대 방정식 직관적 비교 구조 ]

[ 대역폭 (B, Hz) ] ── (돈 주고 산 주파수 폭. 늘리면 속도 비례해서 떡상함)
      │
  (곱하기)
      │
[ 로그 함수 (log₂) ] ── (가성비 깎아 먹는 통곡의 벽)
      │
[ 1 + 신호대잡음비 (S/N) ] ── (쓰레기 잡음 대비 내 진짜 신호가 얼마나 센지)
      │
      ▼
[ 채널 용량 (C, bps) ] ── (이 한계선 넘으면 데이터 다 깨짐)
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **대역폭 (B)** | 넓을수록 속도가 정직하게 올라가는 **통신사의 진짜 밥줄 (Hz 단위)** | 선형 비례 |
| **신호 전력 (S)** | 기지국이나 안테나에서 전력 풀로 땡겨서 **쏘아대는 실제 신호 파워 (와트)** | Signal |
| **잡음 전력 (N)** | 우주나 기계에서 발생하는 **어쩔 수 없는 쓰레기 열잡음 총량 (와트)** | Noise |
| **S/N (선형비)**| 데시벨(dB) 껍데기 벗기고 **진짜 신호가 잡음보다 몇 배 센지 계산한 비율** | Ratio |
| **채널 용량 (C)** | 이 속도 위로는 절대 못 넘는 **물리계층의 절대 뚜껑 (bps 단위)** | Capacity |

#### 한줄 요약

- $C = B \log_2(1+S/N)$ 공식으로 대역폭(선형)과 SNR(비선형)을 비벼서 절대 못 넘는 속도를 계산하는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **구현 격차 (Implementation Gap)**: 섀넌 할아버지는 100Mbps 나온다고 수학으로 증명했지만, 현실 장비 성능이 구려서 70Mbps밖에 못 뽑는 이상과 현실의 눈물 나는 차이다.

</details>

```text
[ 통신 속도 뚜껑 측정 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [대역폭(B) 및 물리 파워 측정]
│ (현장: 주파수 폭이랑 기지국 출력, 잡음량 잼)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [데시벨(dB) ➡️ 선형비 변환]
│ (계산기: 뻥튀기된 dB 치우고 진짜 S/N 비율로 바꿈)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [섀넌 방정식 공식 대입]   │
│ (계산기: C = B * log2(1 + S/N) 수학 돌림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [이론적 뚜껑(최대 용량) 산출]
│ (결과: 오케이 이 환경에선 최대 1Gbps 무조건 나옴!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [구현 격차 빼고 실제 속도 확정]
│ (운영팀: 기계 성능 구리니까 700Mbps로 안전빵 타협)
└──────────────────────────────┘
```

### 동작 원리

1. 현장 측정: 주파수 대역폭(B)과 수신 신호 강도(S), 그리고 바닥에 깔린 잡음 전력(N)을 잼.
2. dB 변환: 현장에서 찍힌 $SNR_{dB}$ 값을 방정식에 넣기 위해 진짜 비율(선형비)로 벗겨냄.
3. 공식 대입: $C = B \log_2(1+S/N)$에 싹 다 집어넣고 계산기 때림.
4. 상한선 도출: "이 물리 환경에서는 절대 1Gbps를 넘을 수 없다"는 이론적 뚜껑이 나옴.
5. 운용 속도 픽스: 기계적 한계(구현 격차)와 마진을 빼서 실제 고객한테 서비스할 속도(타겟 BLER)를 픽스함.

#### 한줄 요약

- 파워 재고 $\to$ 공식에 넣고 수학 돌린 뒤 $\to$ 현실 기계 성능(격차) 감안해서 서비스 속도 픽스하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대역폭 증대 (B 확장)**: 5G에서 주파수 두 개를 묶거나(CA), mmWave 같은 초광대역을 통째로 사 와서 속도를 화끈하게 올리는 돈지랄 확실한 전략이다.
- **SNR 증대 (전력 증폭)**: 기지국 앰프를 급격히 돌려서 파워를 올리는 건데, 전기세만 뒤지게 나가고 로그벽에 막혀서 속도는 별로 안 오르는 가성비 똥망 전략이다.

</details>

| 구분 | **대역폭 증대 (B 확장)** | **SNR 증대 (전력 증폭)** |
|:---|:---|:---|
| 비유 및 핵심 특징 | 차선을 2차선에서 4차선으로 늘리는 **근본 해결책** | 좁은 길에서 앞차 빵빵거리며 엑셀 밟는 **가성비 똥망 짓** |
| 속도 증가 방식 | 대역폭 곱한 만큼 정직하게 늘어나는 **선형 떡상 ($C \propto B$)** |  파워를 아무리 올려도 찔끔 오르는 **로그 통곡의 벽 ($C \propto \log_2$)** |
| 실제 적용 기술 | 주파수 병합(CA), **초광대역(mmWave) 도입** | 기지국 출력 앰프 빵빵하게 틀기, **단순 중계기 복붙 설치** |
| 주요 한계 | 국가에서 허락한 **가용 주파수 자원이 부족하고 조 단위로 개비쌈** | 전기세만 오지게 나가고 **다른 기지국에 전파 간섭(민폐) 오지게 줌** |

#### 한줄 요약

- 파워 올려서 속도 내는 건 가성비 똥망이니까, 진짜 속도 올리고 싶으면 비싸도 주파수(대역폭)를 넓혀야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스펙트럼 효율 (Spectral Efficiency)**: 1Hz짜리 주파수로 1초에 몇 비트(bps/Hz)나 구겨 넣을 수 있는지 따지는 통신사의 '주파수 가성비' 지표다.
- **실제 굿풋 (Goodput)**: 섀넌 공식으로 나온 뻥스펙 말고, 쓸데없는 헤더 찌꺼기 떼고 찐으로 고객 폰 유튜브에 도달한 '체감 속도'다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 섀넌 공식 믿었다가 **현실 속도 안 나와서 고객한테 욕 쳐먹음** | 이론적 최대 뚜껑치($C$)를 진짜 고객이 체감하는 굿풋(Goodput)으로 착각함 | 맥(MAC)/IP 프로토콜 **헤더 오버헤드 찌꺼기 싹 다 빼고 보수적으로 계산** | 뻥스펙 마케팅 방지하고 현실적인 체감 속도 보장 |
| 기지국 파워 올렸는데 **속도는 안 오르고 전파 간섭만 터짐** | SNR 올린다고 기지국 출력 빵빵하게 쐈는데 로그 함수 뚜껑에 막혀 효율이 개판 남 | 무식한 출력 증폭 줄이고, 다중 안테나 쏘는 **Massive MIMO 기술 도입** | 전력 낭비 컷트하고 물리적 공간 분할로 용량 떡상 |
| 대역폭($B$) 늘렸더니 **잡음($N$)도 덩달아 커져서 렉 걸림** |  주파수 폭(B)을 넓히면 우주에서 들어오는 열잡음($N = N_0 \times B$) 총량도 같이 늘어남 | 광대역 쓸 때는 **수신 필터 빡세게 걸고, 신호 쎈 곳 위주로 주파수 배정** | 잡음 억제해서 SNR 떨어지는 거 막고 진짜 광대역 용량 확보 |

#### 한줄 요약

- 공식 믿고 뻥스펙 치지 말고 오버헤드 빼서 굿풋 구하고, 출력만 올리지 말고 다중 안테나(MIMO) 써서 효율 뽑아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 터무니없는 뻥스펙 마케팅과 쓸데없는 송신 전력 낭비를 박살 내기 위해, **로그 둔화(SNR)** 의 한계를 인정하고 주파수 묶음(CA)과 다중 안테나(MIMO)로 우회하는 채널 용량 설계 기조 확립함

#### 한줄 요약

- 섀넌의 채널 용량 공식은 무선 통신의 헛된 환상을 깨부수고, 자본과 기술이 가야 할 팩트의 길을 알려주는 헌법이다.
