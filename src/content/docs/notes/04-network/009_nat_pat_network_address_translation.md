## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NAT (Network Address Translation)**: 사설 IP 주소와 공인 IP 주소 간의 L3 네트워크 주소를 1:1 또는 1:N으로 상호 변환하는 기술 (RFC 1631).
- **PAT (Port Address Translation / NAPT)**: 단일 공인 IP 주소에 L4 포트 번호(1~65535)를 다중화 매핑하여 다수의 사설 IP 호스트가 인터넷을 공유하는 N:1 변환 기술 (NAT Overload).

</details>

- 정의/개념: 사설망 호스트가 인터넷과 통신할 수 있도록 **L3 IP 주소 및 L4 포트 번호를 공인 IP 및 포트로 변환하는 주소 변환 기술**
- 배경/필요성: 32비트 IPv4 공인 주소 공간의 급격한 고갈로 인해 기업 및 가정의 모든 단말에 공인 IP를 직접 부여할 수 없는 물리적 한계와 내부 네트워크 토폴로지 및 호스트 IP가 외부 인터넷에 그대로 노출되는 보안 위협을 해결하기 위해, RFC 1918 사설 IP 공간을 활용하고 게이트웨이 경계에서 L3 IP 및 L4 포트 번호(1~65535)를 공인 튜플로 상호 변환하는 NAT/PAT(NAPT) 기술을 도입하여 **단일 공인 IP 기반의 다수 단말 동시 인터넷 접속(N:1 다중화)과 내부망 은닉 보안**을 달성할 필요

#### 한줄 요약
- 사설 IP를 공인 IP 및 포트로 변환하여 IPv4 주소를 절감하고 내부 호스트를 은닉한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NAT Table (변환 세션 테이블)**: [내부 사설 IP : 사설 포트]와 [외부 공인 IP : 공인 포트] 간의 5-Tuple 매핑 상태를 실시간 기록 및 유지하는 메모리 테이블.
- **ALG (Application Layer Gateway)**: FTP, SIP/VoIP처럼 페이로드 내부에 사설 IP 정보가 포함된 복합 프로토콜을 파싱하여 주소를 변환해 주는 L7 프록시 기능.

</details>

- 단일 공인 IP로 수천 대 단말의 인터넷 동시 접속을 수용하는 **N:1 포트 다중화(PAT)**
- 변환 상태가 없는 외부 요청을 제한하는 **인바운드 도달성 축소**
- L3 IP 및 L4 TCP/UDP 헤더 변환 후 패킷 무결성을 유지하는 **체크섬(Checksum) 실시간 재계산**

#### 한줄 요약
- N:1 포트 다중화, 내부망 은닉 보안, 실시간 체크섬 갱신을 통해 주소 절감과 보호를 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NAT 4대 핵심 구조**: Private IP Space(RFC 1918), Public IP Pool, NAT Translation Table, Checksum Recalculation Engine.

</details>

```text
[NAT 게이트웨이]
|-- 사설 주소 공간
|-- 공인 주소 풀
|-- 변환 세션 테이블
|-- 헤더 변환기
`-- 체크섬 재계산기
```

선의 의미: 계층 및 사설망 패킷이 NAT 장비에서 헤더가 재작성되고 세션 테이블에 등록된 후 공인 인터넷 서버로 전달되는 구조

| 구성요소 | 책임 |
|:---|:---|
| 사설 주소 공간 | 내부 호스트 주소 제공 |
| 공인 주소 풀 | 외부 라우팅 주소 제공 |
| **변환 세션 테이블** | 사설·공인 튜플과 수명주기 매핑 |
| 헤더 변환기 | 출발지·목적지 주소와 포트 치환 |
| 체크섬 재계산기 | 헤더 변경 후 체크섬 갱신 |

#### 한줄 요약
- 변환 세션 테이블이 사설망과 인터넷 경계에 끼어들어 단말마다 필요하던 공인 주소를 소수 공인 튜플의 시분할 매핑으로 대신하고, 체크섬 재계산기가 그 헤더 변경의 뒤처리를 떠맡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PAT 변환 5단계**: 내부 송신 인입 $\to$ 가용 포트 할당 및 세션 기록 $\to$ 출발지 헤더 치환 $\to$ 외부 응답 인입 $\to$ 목적지 헤더 역변환 복원.

</details>

```text
사설 호스트 외부 인터넷 통신 (PAT)
        │
   1. [내부 송신] PC(`192.168.1.10:5000`)가 웹서버(`203.0.113.50:80`)로 패킷 전송
        │
   2. [세션 등록 및 포트 할당] NAT 라우터가 빈 공인 포트(`10001`)를 배정하고 테이블에 등록
        │
   3. [헤더 변환 및 전송] 출발지 `192.168.1.10:5000` -> `203.0.113.1:10001` 치환 및 체크섬 갱신
   ┌────┴───────────────────────────┐
  외부 응답 패킷 정상 도착        세션 타임아웃 만료
   │                                 │
4. [테이블 역조회 및 헤더 복원]     • 세션 정보 자동 삭제 (회수)
    목적지 `203.0.113.1:10001`을 `192.168.1.10:5000`으로 원복
   │
   ▼
5. [내부 단말 인계] 복원된 패킷을 내부 사설망 PC에 최종 전달 완료
```

- 1. 내부 송신: 사설 호스트의 외부 요청 수신
- 2. 세션 등록 및 포트 할당: 공인 튜플 매핑 생성
- 3. 헤더 변환 및 전송: 출발지 주소·포트 치환
- 4. 테이블 역조회 및 헤더 복원: 내부 튜플 복구
- 5. 내부 단말 인계: 복원된 응답 전달

#### 한줄 요약
- 응답이 제때 오면 역조회 한 번으로 원래 튜플이 복원되지만 타임아웃으로 세션이 회수된 뒤에는 복원 근거가 사라지므로, 변환 계층의 비용은 세션 상태를 얼마나 오래 들고 있느냐로 나타난다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 정적 NAT (Static NAT) | 동적 NAT (Dynamic NAT) | 포트 주소 변환 (PAT / NAPT) |
|:---|:---|:---|:---|
| 매핑 비율 | 1:1 | N:M | N:1 |
| 적용 대상 | 공개 서버 | 임시 공인 주소 요구 | 일반 사용자 단말 |
| 인바운드 연결 | 고정 매핑으로 가능 | 활성 매핑 동안 가능 | 포트 포워딩 시 가능 |
| 주소 효율 | 낮음 | 보통 | 높음 |

#### 한줄 요약
- 공개 서버는 정적 NAT, 임시 대여는 동적 NAT, 일반 다수 단말은 PAT를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Port Forwarding (포트 포워딩)**: PAT 환경에서 외부의 특정 공인 포트 요청을 내부 사설 서버의 특정 IP 및 포트로 1:1 고정 우회시키는 설정.
- **NAT Port Exhaustion (포트 고갈)**: 대량의 동시 세션(P2P/크롤링)으로 인해 사용 가능한 65,535개 공인 포트 풀이 고갈되어 신규 연결이 실패하는 장애.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대량 세션 폭주로 공인 포트(65,535개) 고갈(**Port Exhaustion**) 장애 | 복수 공인 IP 풀 구성 및 유휴 세션 타임아웃 단축 | 포트 고갈 방지 및 신규 세션 수용 |
| FTP/SIP 등 페이로드 내 사설 IP가 포함된 프로토콜 통신 실패 | 라우터·방화벽에서 프로토콜별 **ALG** 활성화 | 복합 L7 프로토콜 주소 변환 보장 |
| 침해 사고 발생 시 다수 단말이 동일 공인 IP를 공유하여 추적 불가 | NAT 변환 로그(사설 IP-포트-시간-공인 IP)를 중앙 SIEM에 실시간 적재 | 법적 컴플라이언스 및 역추적성 확보 |
| PAT 내부망에 위치한 서버로 외부 클라이언트 접속 불가 | 외부 특정 포트를 내부 서버로 매핑하는 **Port Forwarding**(DNAT) 구성 | 사설망 내 공개 서비스 안전 배포 |

#### 한줄 요약
- NAT는 주소를 절약하는 대가로 경계 장비에 세션 상태를 쌓으므로, 실무 대책은 그 상태의 용량(포트 풀·타임아웃)·예외(ALG·포트 포워딩)·기록(로그)을 관리하는 비용으로 귀결된다.

## Ⅶ. 결론

- IPv6 전면 전환 전까지 IPv4 주소 생명을 연장하고 엔터프라이즈 사내망 및 클라우드 VPC NAT Gateway의 기본 인프라로 확립되었으며, 실무 운영 시에는 **대량 동시 세션 폭주 시 포트 고갈(Port Exhaustion)을 방지하는 다중 공인 IP 풀 구성 및 유휴 세션 타임아웃 최적화, FTP/SIP 등 복합 프로토콜 처리를 위한 ALG(Application Layer Gateway) 활성화, 보안 침해 사고 역추적을 위한 NAT 세션 변환 로그의 SIEM 실시간 연동, 사설망 서버 서비스를 위한 포트 포워딩(DNAT)**을 결합하여 가용성과 추적성을 동시에 완성

#### 한줄 요약
- NAT/PAT는 사설-공인 IP 및 포트 변환을 통해 IPv4 고갈을 극복하고 내부망을 보호하며, ALG와 포트 포워딩을 통해 서비스 연속성을 보장하는 핵심 네트워크 기술이다.
