## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 주소 변환(NAT, Network Address Translation)**: 가짜 주소(사설 IP)를 쓰는 사내 PC들이 바깥세상(인터넷)이랑 통신할 수 있게, 라우터가 진짜 주소(공인 IP)로 이름을 싹 바꿔주는 신분 세탁 기술이다.
- **포트 주소 변환(PAT, Port Address Translation)**: 비싼 공인 IP 하나에다 방 번호(포트)만 수만 개로 쪼개서, 사내 PC 여러 대가 공인 IP 하나로 인터넷을 같이 돌려쓰는 눈물겨운 N:1 꼼수이다.

</details>

- 정의: 통신이 안 되는 사설 주소를 라우터에서 공인 주소와 포트로 치환해 주는 **NAT•PAT**
- 배경: 32비트 IPv4로는 기하급수적으로 늘어나는 **스마트폰과 PC의 공인 주소 수요를 감당할 수 없었기 때문** #### 한줄 요약

- 모자란 공인 IP 하나로 사내 PC 전체가 포트만 나눠서 인터넷을 할 수 있게 만든 돌려막기 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상태 기반 NAT(Stateful NAT)**: 안에서 밖으로 나간 패킷만 기억해 뒀다가, 그 패킷에 대한 답장만 안으로 들여보내 주는 똑똑한 문지기 역할이다.
- **변환 테이블(NAT Table)**: "안쪽 192.168.0.5의 3000번 포트를 바깥쪽 203.0.113.1의 5000번 포트로 바꿔서 내보냈다"라고 적어두는 장부이다.

</details>

- **상태 기반 NAT(Stateful NAT)** 동작을 통해 내부에서 시작된 트래픽의 응답 패킷만 안전하게 수신 및 역변환 처리.
- **포트 주소 변환(PAT)** 메커니즘으로 공인 IP 1개당 최대 64,000여 개의 소켓(포트)을 맵핑하여 공인 주소 자원 낭비 최소화.
- 동적 세션 만료 타이머를 가진 **변환 테이블** 굴려 보안 격리성과 IP 재활용성 확보.

#### 한줄 요약

- 공인 IP 하나에 포트 번호 수만 개를 쪼개 팔고, 나간 놈만 장부에 적어뒀다 들여보내는 시스템이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 IP 주소(Private IP Address)**: `192.168.x.x`처럼 집이나 회사 안에서만 통하는 가짜 돈이라 인터넷에선 라우팅이 막힌다.
- **공인 IP 주소(Public IP Address)**: 통신사에 돈 내고 빌려 쓰는, 전 세계 어디서든 라우팅이 빵빵 뚫리는 진짜 돈이다.

</details>

```text
[ NAT/PAT 기반 직관적 비교 변환 아키텍처 ]

[ 사내망 PC ]                                        [ 외부 인터넷 서버 ]
192.168.1.10:50001 (사설 5-튜플)                        203.0.113.50:80
         │
         │ (나 웹서버 갈래)
         ▼
┌───────────────────────────────────────────┐
│              [ NAT 장비 ]                 │
│ 1. 변환 장부(NAT Table)에 매핑 기록함     │
│ 2. 사설 IP/Port -> 공인 IP/Port로 덧칠함  │
│ 3. 덧칠했으니까 무결성(체크섬) 다시 계산함│
└───────────────────────────────────────────┘
         │
         │ (신분 세탁 완료)
         ▼
203.0.113.1:10001 (공인 5-튜플) ───────────────▶ 203.0.113.50:80
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **사설 IP 주소** | 회사 안에서만 노나 쓰는 짭 주소 | 인터넷에 던지면 바로 버려짐(라우팅 불가) |
| **공인 IP 주소** | 인터넷에서 통하는 찐 주소 | 라우터 **주소 풀(Pool)** 에서 동적 할당 |
| **변환 테이블(NAT Table)**| [내부 짭 주소+포트] $\leftrightarrow$ [외부 찐 주소+포트]를 묶어놓은 장부 | 라우터 메모리(TCAM) 점유함 |
| **체크섬 재계산** | 헤더의 주소를 조작했으니까, 에러 안 나게 체크섬 값도 다시 갱신해 줌 | 패킷 훼손 오탐지 방지 |

#### 한줄 요약

- 사설 IP 패킷을 뜯어서 공인 IP로 덧칠하고, 들키지 않게 체크섬까지 조작해서 내보낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **송신 튜플 변환(Outbound Tuple Translation)**: 사설망에서 바깥으로 나갈 때 출발지 IP와 포트를 공인 IP와 임의의 포트로 덮어쓰고 장부에 적는 과정이다.
- **수신 튜플 복원(Inbound Tuple Restoration)**: 밖에서 응답이 오면 장부를 보고 원래 사설 IP와 포트로 되돌려놔서 주인을 찾아주는 과정이다.

</details>

```text
[ PAT 송수신 변환 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 내부망 출발 (송신)        │
│ (Src: 192.168.1.10:5000)     │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 장부 기록 & 포트 할당     │
│ (공인 203.0.113.1:1000 배정) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 송신 헤더 변환 & 발사     │
│ (Src 덮어쓰고 체크섬 갱신)   │
└──────────────┬───────────────┘
               ▼ (인터넷 통과 후 응답 도달)
┌──────────────────────────────┐
│ 4. 수신 장부 역조회          │
│ (Dst: 203.0.113.1:1000 도착) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 수신 헤더 복원            │
│ (Dst 192.168.1.10으로 원복)  │
└──────────────────────────────┘
```

### 동작 원리

1. 내부망 출발: 사설 IP 단말이 외부 인터넷으로 패킷을 쏨.
2. 장부 기록: 라우터가 빈 공인 포트를 찾아서 장부에 묶어둠.
3. 송신 튜플 변환: 출발지 주소와 포트를 덮어쓰고 체크섬을 갱신해 인터넷으로 발사함.
4. 수신 장부 역조회: 외부에서 목적지로 도착한 응답 패킷을 받음.
5. 수신 튜플 복원: 장부를 보고 원래 사설 IP로 목적지를 복원해 내부 단말에 넘겨줌.

#### 한줄 요약

- 나갈 때 장부 적고 이름표 싹 바꿔치기한 다음, 들어올 때 장부 보고 원래 주인한테 돌려준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 NAT(Static NAT)**: 사내 웹 서버처럼 밖에서 뚫고 들어와야 하는 애를 위해 공인 IP 하나를 전세 내서 평생 고정해 주는 비싼 방식이다.
- **동적 NAT(Dynamic NAT)**: 공인 IP 여러 개를 묶어두고 직원들이 인터넷 할 때마다 선착순으로 1:1로 빌려주고 회수하는 방식이다.

</details>

| 분류 | **정적 NAT (1:1 고정 전세)** | **동적 NAT (1:1 선착순 대여)** | **PAT / NAT Overload (N:1 합숙)** |
|:---|:---|:---|:---|
| 매핑 비율 | **1 : 1 (평생 고정)** | N : M (잠깐씩 1:1) | **N : 1 (포트 쪼개서 다 같이 씀)** |
| 주 활용 대상 | 무조건 외부 노출 필요한 **웹/DB 서버** | 보안상 공인 IP 잠깐 쓸 때 | 일반 사내망 PC, 스마트폰 전체 |
| 주요 특징 | 밖에서 사내 서버로 **직접 핑 때리기 완전 지원** | 주소 풀 꽉 차면 **다음 사람 인터넷 안 됨** | **공인 IP 1개** 기반 최대 수만 명 동시 접속 수용 |
| 효율성/보안성| 공인 IP 자원 낭비 / 노출 위험 높음 | 자원 낭비 심함 / 중간 | **자원 효율 미침 / 밖에서 직접 연결 불가(안전)** |

#### 한줄 요약

- 서버는 정적 NAT로 1:1로 빼주고, 직원 폰과 PC는 PAT로 묶어서 공인 IP 하나로 다 때운다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포트 포워딩(Port Forwarding)**: "PAT 쓰면 밖에서 못 들어온다고? 그럼 공인 IP 80번 포트로 오면 무조건 사내 서버 80번으로 토스해!" 하고 라우터에 구멍을 뚫어주는 거다.
- **응용 계층 게이트웨이(ALG)**: FTP나 VoIP처럼 알맹이(페이로드) 안에 사설 IP를 적어놓는 애들을 위해, 라우터가 알맹이까지 까서 주소를 변환해 주는 똑똑한 기능이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| P2P나 토렌트 돌리다 **PAT 포트 6만 개 다 써서 인터넷 먹통됨** | 공인 IP 주소 풀 넉넉하게 추가 및 **세션 타임아웃 튜닝** | 포트 고갈로 인한 접속 단절(Port Exhaustion) 장애 예방 |
| FTP 쓰는데 헤더만 바꾸고 알맹이에 사설 IP 냅둬서 **응답 안 옴** | 해당 프로토콜 페이로드까지 까서 바꿔주는 **ALG 활성화** | 복합 응용 프로토콜의 통신 붕괴 방지 |
| 범죄 터졌는데 다 똑같은 공인 IP라 **누구 PC인지 추적이 안 됨** | 사설 IP와 포트 묶인 시간 다 기록하는 **변환 매핑 로그 중앙 수집(SIEM)** | 사설 IP 사용자의 직관적 비교 역추적 가능 |
| PAT 때문에 밖에서 우리 회사 **서버로 접속을 못 함** | 외부 포트와 사내 서버 IP를 딱 찍어주는 **포트 포워딩 설정** | 밖에서도 사설망 서버 접속 수용 가능 |

#### 한줄 요약

- PAT 때문에 서버 접속 막힌 건 포트 포워딩으로 뚫고, 알맹이에 IP 숨긴 건 ALG로 처리해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NAT 방식 선택(NAT Strategy Selection)**: 서버면 정적 NAT를 주고, 직원 PC면 PAT로 묶어서 공인 IP 돈을 아끼는 실무적인 설계 원칙이다.

</details>

- **NAT 방식 선택** 원칙에 따라, 외부 도달성이 필요한 서버는 **정적 NAT(또는 포트 포워딩)**, 일반 단말은 **PAT** 활용 혼용 적용하는 기조 확립함

#### 한줄 요약

- 밖에서 들어와야 하는 서버는 포트 포워딩이나 정적 NAT를 주고, 나머지는 다 PAT로 돌려라.
