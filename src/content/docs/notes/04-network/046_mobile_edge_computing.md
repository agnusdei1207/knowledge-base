## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모바일 엣지 컴퓨팅(Multi-access Edge Computing, MEC)**: 이동통신 기지국 인접 지점(Edge)에 클라우드 컴퓨팅 서버와 스토리지 인프라를 배치하여, 대용량 트래픽을 중앙 코어망으로 전송하지 않고 로컬에서 즉시 연산·처리하는 분산 컴퓨팅 아키텍처 (ETSI 표준).
- **로컬 트래픽 분기(Local Breakout, LBO)**: 기지국에서 수신된 사용자 평면(U-Plane) 패킷을 중앙 코어망(UPF)으로 라우팅하기 전에, 기지국 인근의 로컬 UPF를 통해 현장 사내망이나 MEC 호스트로 직접 분기 처리하는 기술.

</details>

- 정의/개념: 무선 기지국(gNB) 및 접속망 종단에 IT 컴퓨팅 자원과 **Local UPF** 를 전진 배치하여, **로컬 오프로딩(LBO)** 과 **초저지연(1~5ms) 데이터 처리** 를 제공하는 **ETSI 표준 엣지 클라우드 기술(MEC)**
- 배경/필요성: 중앙 데이터센터 왕복에 따른 물리적 전송 지연(30~100ms)과 백홀 네트워크 대역폭 포화를 해소하고, 자율주행(V2X), 스마트 팩토리, 원격 의료의 실시간 결정론적 SLA를 보증할 요구

#### 한줄 요약
- 기지국 인접 지점에 컴퓨팅과 로컬 UPF를 전진 배치하여 왕복 지연을 단축하고 백홀 부하를 완화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **무선망 정보 서비스(Radio Network Information Service, RNIS)**: MEC 플랫폼에서 구동되는 응용 앱이 무선 기지국의 실시간 채널 품질(CQI), 셀 부하 상태, 단말 위치 정보를 API(RESTful) 형태로 조회할 수 있도록 제공하는 서비스.
- **데이터 상주성(Data Residency) 및 데이터 주권**: 민감한 공정 데이터나 개인정보가 중앙 공용망으로 유출되지 않고 수집된 로컬 사이트 내에 안전하게 격리 보관되는 보안적 특성.

</details>

- **초저지연 로컬 오프로딩**: 단말 인접(수백 미터~수 킬로미터) 위치에서 트래픽을 즉시 처리하여 RTT를 1~5ms 수준으로 단축
- **백홀 대역폭 절감 및 데이터 주권 확보**: 고용량 CCTV 영상이나 센서 데이터를 로컬에서 전처리하여 백본망 트래픽을 80% 이상 절감하고 기밀 유출 차단
- **무선망 인지형 컨텍스트 서비스(RNIS)**: 기지국 채널 품질 및 혼잡도 정보를 실시간 피드백받아 비디오 비트레이트 및 QoS를 동적 적응 제어

#### 한줄 요약
- 1ms 초저지연, 백홀 트래픽 절감, 데이터 주권 보호, RNIS 기반 무선망 인지 서비스를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **MEC 오케스트레이터(MEO / MEC Orchestrator)**: 다수의 분산 MEC 호스트 전체의 자원 가용성을 파악하고 SLA 요구사항에 따라 엣지 응용 패키지의 배치 및 생애주기를 총괄하는 최상위 관리자.
- **MEC 플랫폼(MEC Platform, MEP)**: 개별 엣지 서버 내부에서 엣지 응용 프로그램(MEC App)이 구동될 수 있는 런타임 환경을 제공하고 RNIS, 위치 서비스 등의 API를 중계하는 플랫폼.

</details>

```text
[ MEC 시스템 레벨 관리 (MEO / MEC Orchestrator) ]
   │ (엣지 앱 라이프사이클 관리 및 배포 제어)
   │
   ▼ (Mm3 / Mm1 인터페이스)
┌────────────────────────────────────────────────────────────┐
│ MEC Host (기지국 인접 엣지 서버)                           │
│ ├─ [ MEP (MEC 플랫폼) ] ── (RNIS, Location API, DNS 제공)  │
│ └─ [ MEC Apps (초저지연 자율주행 / 비전 AI 앱) ]           │
└─────────────────────────────▲──────────────────────────────┘
                              │ (Local Breakout 분기 경로)
[ Local UPF (로컬 패킷 분기) ] ◀── [ 5G gNB ] ◀── [ 단말 (UE) ]
                              │ (인터넷 / 비엣지 일반 트래픽)
                              ▼
[ 중앙 5G 코어망 (5GC / Central UPF) ] ──▶ 외부 인터넷
```

선의 의미: 기지국에서 수신된 트래픽 중 초저지연 요청은 Local UPF를 통해 MEC Host로 즉시 분기되고, 일반 트래픽은 중앙 5GC로 전송되는 이중 경로 구조

| 구성요소 | 책임 | 표준 인터페이스 |
|:---|:---|:---|
| **MEC 오케스트레이터 (MEO)** | 전체 분산 엣지 호스트의 자원 토폴로지 관리 및 SLA 기반 앱 자동 배치 | Mm1, Mm3 |
| **MEC 플랫폼 (MEP)** | 엣지 앱 등록, 통신 메시 분기, 무선망 정보(RNIS) 및 위치 서비스 API 제공 | Mp1, Mp2 |
| **Local UPF (LBO)** | 5GC SMF의 트래픽 조향 규칙(Traffic Steering)에 따라 엣지 트래픽을 로컬 분기 | N3, N6, N9 |
| **MEC Apps (엣지 응용)** | 가상화 컨테이너 기반으로 구동되는 실시간 분석, AI 추론 및 V2X 관제 모듈 | Mp1 연동 |

#### 한줄 요약
- MEO, MEP, Local UPF, MEC Apps가 결합하여 기지국 종단에서 분산 클라우드 서비스를 완성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터망 접근 식별자(Data Network Access Identifier, DNAI)**: 5G 코어망에서 사용자 세션이 특정 로컬 엣지 데이터망(MEC)으로 라우팅되도록 지정하는 식별자.

</details>

```text
1. MEO가 서비스 지연 요구사항 분석 후 최적의 엣지 호스트(MEC Host)에 컨테이너 앱 배포
            │
            ▼
2. MEP가 5GC 코어(SMF/NEF)로 트래픽 조향 규칙(DNAI 매핑 및 LBO 라우팅) 등록
            │
            ▼
3. 단말이 gNB로 데이터 전송 ➔ Local UPF가 패킷 검사(PDR)를 통해 LBO 경로 식별
            │
            ▼
4. Local UPF가 사용자 트래픽을 중앙 코어 경유 없이 사내 MEC App으로 즉시 포워딩 (1ms)
```

**동작 원리**

1. **엣지 앱 프로비저닝**: MEO가 지리적 부하 분산 정책에 따라 대상 기지국 인근 MEC 호스트에 인스턴스 기동
2. **트래픽 조향 룰 주입**: SMF가 N4(PFCP)를 통해 Local UPF에 특정 대상 IP/포트 트래픽의 로컬 분기 규칙(FAR) 설정
3. **로컬 오프로딩 실행**: 단말의 업링크 패킷이 기지국을 거쳐 Local UPF 인입 시 N6 인터페이스를 통해 MEC Host로 즉각 우회 전달
4. **초저지연 응답**: 엣지 앱이 데이터를 즉각 연산한 후 다운링크 피드백을 단말로 1ms 내 직접 반환

#### 한줄 요약
- 엣지 앱 배포, 트래픽 조향 룰 주입, Local UPF 패킷 분기, 초저지연 로컬 연산 및 응답 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 집중형 클라우드(Central Cloud)**: 대규모 데이터센터(IDC)에 수만 대의 서버를 집중 배치하여 규모의 경제와 대용량 배치 처리를 제공하는 전통적 클라우드.

</details>

| 비교 항목 | 모바일 엣지 컴퓨팅 (MEC) | 중앙 집중형 클라우드 (Central Cloud) |
|:---|:---|:---|
| **배치 위치** | **기지국(gNB), 국사, 온프레미스 현장 (Edge)** | 대규모 리전 데이터센터 (수백 km 원거리) |
| **네트워크 지연 (RTT)** | **1 ~ 10 ms (결정론적 초저지연)** | 30 ~ 100 ms (공용 백본 전송 지연) |
| **백홀 트래픽 부하** | **현장 처리로 백홀 트래픽 대폭 절감** | 모든 트래픽이 백본망을 통과하여 병목 유발 |
| **무선망 인지(RNIS)** | **가능 (기지국 채널/위치 정보 API 활용)** | 불가능 (무선 계층 정보 접근 불가) |
| **적합 서비스** | **자율주행(V2X), 스마트 팩토리, 원격 수술** | 대규모 빅데이터 분석, LLM 학습, 중앙 DB |

#### 한줄 요약
- MEC는 기지국 인접 배치로 초저지연과 데이터 주권을 보장하고, 중앙 클라우드는 대규모 연산 처리를 전담한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상태 컨텍스트 재배치(Context Relocation)**: 단말이 이동하여 접속 기지국과 서빙 MEC 호스트가 변경될 때, 이전 엣지 서버의 활성 세션 상태(State)를 신규 엣지 서버로 고속 복제·이관하는 기술.
- **원격 무결성 증명(Remote Attestation)**: 외부에 분산 배치된 엣지 하드웨어의 부팅 무결성과 변조 여부를 신뢰 플랫폼 모듈(TPM) 기반으로 원격 검증하는 보안 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단말 고속 이동 시 서빙 기지국 전환에 따른 엣지 앱 세션 단절 | **상태 컨텍스트 재배치(Context Relocation)** 및 L3 세션 인계 메커니즘 적용 | 엣지 간 핸드오버 시 지연 없는 서비스 연속성 유지 |
| 물리적 보안이 취약한 분산 국사 엣지 서버의 물리 변조 및 침해 위협 | 하드웨어 **TPM 기반 원격 무결성 증명(Remote Attestation)** 의무화 | 비인가 펌웨어 위변조 탐지 및 제로 트러스트 엣지 보안 확립 |
| 트래픽 조향 룰 오류로 인한 로컬 패킷의 중앙 코어망 오라우팅 누수 | **DNAI(데이터망 접근 식별자) 자동 검증** 및 패킷 필터링 감사 적용 | 로컬 트래픽 오프로딩 누락 방지 및 데이터 주권 보증 |

#### 한줄 요약
- Context Relocation으로 이동성을 보장하고, TPM 원격 증명으로 물리 보안을 확보하며, DNAI 검증으로 라우팅 누수를 차단한다.

## Ⅶ. 결론

- 초저지연 미션 크리티컬 서비스와 데이터 주권 확보를 위해 **ETSI 표준 MEC 아키텍처**와 **Local UPF** 기반 오프로딩을 기지국 종단에 전진 배치하되, 분산 인프라의 이동성과 보안 취약점을 해결하기 위해 **Context Relocation** 과 **TPM 기반 원격 무결성 검증**을 결합하여 고신뢰 엣지 컴퓨팅 생태계를 완성

#### 한줄 요약
- Local UPF 오프로딩과 TPM 기반 무결성 검증을 결합하여 고신뢰 모바일 엣지 컴퓨팅 환경을 구현한다.
