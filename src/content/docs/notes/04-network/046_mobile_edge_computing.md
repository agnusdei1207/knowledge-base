## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MEC(모바일 엣지 컴퓨팅)**: 통신사 서울 본사(코어망)까지 데이터를 안 보내고, 동네 기지국 바로 옆에 클라우드 서버를 통째로 갖다 놔서 데이터를 0.001초 만에 바로 처리해버리는 기술이다.
- **LBO(Local Breakout)**: 데이터가 코어망 백본으로 빠져나가기 전에, 기지국단(에지)에서 톨게이트 샛길을 뚫어서 바로 사내망(MEC 서버)으로 꺾어버리는 치트키다.

</details>

- 정의: 5G 무선 기지국 근처(Edge)에 컴퓨팅(CPU) 자원과 로컬 라우팅 기능(Local UPF)을 전진 배치하여, 트래픽을 중앙망 경유 없이 **현장에서 즉시 오프로딩(LBO) 처리하는 분산 클라우드 기술**
- 배경: 아마존이나 구글 본사 서버까지 갔다 오면 아무리 빨라도 핑이 30~100ms가 넘는데, 자율주행이나 불량품 검사(머신 비전)는 **0.001초(1ms)만 늦어도 대형 사고가 발생하기 때문**

#### 한줄 요약

- 스마트폰 데이터를 서울(코어망)까지 안 보내고, 동네 기지국 지하실(에지 서버)에서 짬 처리해서 핑을 1ms로 깎아버리는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **RNIS(Radio Network Information Service)**: 에지 서버(MEC)에 깔린 앱이 기지국의 은밀한 정보(전파 세기, 단말기 위치)를 실시간으로 엿볼 수 있게 해주는 특별한 API 규격이다.
- **Local UPF**: 단말기 데이터가 서울까지 안 가게 막고, 기지국단에서 MEC 서버로 패킷을 휙 꺾어버리는 로컬 라우터(골목대장)다.

</details>

- **로컬 트래픽 짬 처리(오프로딩)**: Local UPF를 써서 기밀 데이터나 무거운 CCTV 영상이 중앙 코어망 백본에 올라가기 전에 동네 선에서 다 지지고 볶고 끝내버림.
- **초저지연 및 데이터 잔류성 (보안)**: 서버가 단말기 바로 앞(수백 미터)에 있으니까 핑이 1ms대로 급격한 저하하고, 사내 데이터가 통신사 밖으로 1mm도 안 나가서 보안이 완벽함.
- **무선망 정보 스틸 (RNIS API)**: MEC 앱이 기지국과 직통으로 대화해서, 전파가 약해지면 알아서 영상 화질을 낮추는 등 실시간 밀착 관리가 가능함.

#### 한줄 요약

- 핑 짧고(초저지연), 데이터 밖으로 안 새고(보안), 백본망 발생하는 것도 막아주며(트래픽 감소), 기지국 전파 상태까지 꿰차고(RNIS) 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **MEP(MEC Platform)**: 에지 서버 안에서 앱들을 굴려주고, 무선망 정보(RNIS)를 앱들한테 뿌려주는 실질적인 에지 운영체제(OS)다.
- **MEO(MEC 오케스트레이터)**: 전국에 널려있는 수천 개의 에지 서버를 관리하면서, "강남역 에지에 트래픽 몰리니까 앱 하나 더 깔아!" 하고 지시하는 총사령관이다.

</details>

```text
[ ETSI MEC 직관적 비교 구조 ]

[ MEO (전국 에지 총사령관) ]
      │ (앱 설치 명령)
      ▼
[ MEC Host (동네 기지국 옆 에지 서버) ]
  ├─ [ MEP (에지 운영체제 및 API 제공) ]
  └─ [ MEC Apps (초저지연 자율주행 앱 등) ]
      ▲
      │ (로컬 브레이크아웃 샛길)
[ Local UPF (골목대장 라우터) ] ◀── [ 5G 기지국 ] ◀── [ 스마트폰 ]
      │ (찌꺼기 데이터만 전송)
      ▼
[ 서울 5G 코어 백본 (5GC / 인터넷) ]
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **MEO (총사령관)** | 전국 기지국 자원 파악해서 **어디 에지에 무슨 앱 깔지 결정하는 대빵** | 오케스트레이션 |
| **Local UPF (샛길)** | 기지국에서 올라온 트래픽을 **서울 안 보내고 에지 서버로 꺾어버리는 놈** | 패킷 분기 |
| **MEP (에지 OS)** | 에지 서버 안에서 앱들 굴려주고, 기지국 **전파 정보(API) 물어다 주는 놈** | 플랫폼 |
| **MEC Apps (미니 앱)**| 에지 서버에 깔려서 **자율주행, AR 렌더링을 0.1초 만에 해치우는 놈** | 에지 응용 |

#### 한줄 요약

- 대빵(MEO)이 지시하면, 샛길(UPF)로 데이터 빼돌려서, 운영체제(MEP) 위에서 앱(App)이 0.1초 만에 처리하고 응답하는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **트래픽 조향(Traffic Steering)**: 코어망(SMF)이 Local UPF한테 "유튜브는 서울로 보내고, 자율주행 핑은 에지로 꺾어라" 하고 길을 정해주는 작업이다.

</details>

```text
[ MEC 에지 오프로딩 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [MEO의 에지 앱 깔기 (배치)]
│ (총사령관: 동네 기지국에 자율주행 앱 띄워)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [MEP의 샛길 요청]         │
│ (OS: 코어망아, 자율주행 데이터는 나한테 줘)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [트래픽 조향 룰(LBO) 세팅]│
│ (코어망: ㅇㅋ, UPF야 걔 데이터는 꺾어라)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [기지국단 초저지연 연산]  │
│ (데이터가 서울 안 가고 동네에서 끝남)
└──────────────────────────────┘
```

### 동작 원리

1. 에지 앱 배치: MEO 대빵이 강남역 트래픽이 발생하는 걸 보고, 강남역 에지 서버에 자율주행 앱(컨테이너)을 깔아버림.
2. 조향 룰(Steering Rule) 요청: 에지 OS(MEP)가 서울 코어망(SMF)한테 "스마트폰에서 자율주행 데이터 올라오면 나한테 넘겨"라고 신청함.
3. Local UPF 샛길 오픈: 코어망(SMF)이 끄덕하고, 동네 라우터(Local UPF)한테 해당 데이터 경로를 에지로 꺾으라고 지시함.
4. 초저지연 로컬 처리: 스마트폰 패킷이 기지국에 닿자마자 UPF가 에지 서버로 휙 던져버려서 1ms 만에 처리가 끝남.

#### 한줄 요약

- 에지 서버에 앱 깔고 $\to$ 코어망한테 샛길 열어달라 하고 $\to$ UPF가 데이터 꺾어주면 $\to$ 에지에서 빛의 속도로 짬 처리함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 클라우드(Central Cloud)**: 아마존 AWS나 구글 GCP처럼 엄청 큰 데이터센터에 서버를 수만 대 쑤셔 박아놓은 무식하게 크고 먼 클라우드다.

</details>

| 구분 | **모바일 에지 컴퓨팅 (MEC)** | **중앙 클라우드 (Central Cloud)** |
|:---|:---|:---|
| 핵심 특징 | 집 앞 1분 거리 **동네 편의점** | 차 타고 1시간 가야 하는 **코스트코 대형마트** |
| 서버 위치 | **우리 동네 기지국 지하실** (수백 미터 내외) | **서울, 판교 대형 데이터센터** (수백 km 이상) |
| 반응 핑(RTT) | 1ms ~ 10ms **(눈 깜짝할 새 처리 됨)** | 30ms ~ 100ms **(FPS 게임하면 욕 나옴)** |
| 트래픽 처리 | Local UPF 샛길로 **동네 밖을 안 벗어남** | 통신사 망 다 거치고 **백본 대역폭 다 갉아먹음** |
| 특화 기능 (API) | 기지국 통신 상태 엿보기 **(RNIS) 가능** | 멀어서 통신 상태 알 수가 없음 **(불가능)** |
| 주특기 (사용처) | **자율주행, 불량품 AI 검사, 원격 수술** | 대용량 DB 저장, 글로벌 빅데이터 AI 학습(LLM) |

#### 한줄 요약

- 속도가 생명이면 동네 편의점(MEC)으로 가고, 무겁고 복잡한 거 쌓아둘 땐 코스트코(중앙 클라우드)로 가라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Context Relocation**: 차 타고 이동해서 동네 기지국(에지)이 바뀌어도, 쓰던 앱 데이터를 옆 동네 에지 서버로 초고속 복붙해서 안 끊기게 해주는 기술이다.
- **Remote Attestation(원격 증명)**: 에지 서버는 동네 길거리나 후미진 국사에 있어서 도둑이나 해커한테 침해당하기 쉬우니까, 하드웨어가 개조 안 됐는지 원격으로 체크하는 보안 기능이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 옆 동네 기지국으로 넘어가니 **자율주행 앱이 뚝 끊김** | 스마트폰은 옆 동네로 갔는데 **데이터는 아직 옛날 에지 서버에 남아서 발생 (세션 이탈)** | Stateful **Context Relocation** 빡세게 돌려서 앱 데이터를 옆 에지로 고속 복붙함 | 차 타고 서울-부산 가도 핑 안 튀고 초저지연 유지 |
| 에지 서버가 뒷골목에 있어서 **해커가 와서 털어감** | 철통 보안인 대형 데이터센터와 달리 **물리적 방어가 허술함 (물리 해킹 노출)** | TPM 칩 박아놓고 **Remote Attestation(원격 무결성 증명)** 빡세게 돌림 | USB 꽂아서 바이러스 심거나 깡통 서버 만드는 거 컷 |
| 로컬 샛길(LBO) 뚫었는데 **트래픽이 자꾸 서울로 줄줄 샘** | 코어망(SMF)이 라우터(UPF)한테 **트래픽 조향(Steering) 룰을 엉뚱하게 내려서 발생** | **DNAI(데이터망 접속 식별자)** 매핑 자동 검증 로직 도입 및 방어 | 로컬 패킷 안 새고 100% 에지 서버로 깔끔하게 꽂힘 |

#### 한줄 요약

- 차 타고 기지국 넘어가면 데이터도 같이 퀵으로 보내주고(Context Relocation), 길바닥 서버 털릴까 봐 원격으로 감시 빡세게(TPM) 해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 지연 시간과 프론트홀 대역폭의 한계를 극복하기 위해, **Local UPF** 기반 오프로딩(LBO)과 **MEP** 플랫폼을 기지국 종단에 전진 배치하여 초저지연과 데이터 주권을 실현하는 **MEC** 아키텍처 기조 확립함

#### 한줄 요약

- MEC는 통신망의 중심을 서울(코어망)에서 동네 기지국(에지)으로 끌어내려, 1ms의 벽을 깨고 자율주행 시대를 여는 핵심 열쇠다.
