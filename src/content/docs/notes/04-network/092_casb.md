## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CASB (클라우드 접근 보안 브로커)**: 직원들이 회사 몰래 구글 드라이브나 드롭박스 같은 외부 클라우드(SaaS)에 기밀 문서를 올리는지 감시하고, 유출을 막아주는 클라우드 전용 보안 경찰(Proxy)이다.
- **섀도 IT (Shadow IT)**: 보안팀이나 IT 부서 허락도 안 받고 직원들 맘대로 쓰는 외부 클라우드 서비스다. (예: 개인용 카카오톡, 웹하드로 도면 빼돌리기)

</details>

- 정의: **CASB** 기반 온프레미스 사용자와 외부 클라우드 서비스(SaaS/IaaS) 사이에 끼어들어서, 직원들의 클라우드 사용 가시성을 확보하고 데이터 유출(DLP)을 차단하는 보안 중개 솔루션이다.
- 배경: 재택근무가 늘면서 직원들이 통제 안 되는 개인 클라우드(섀도 IT)에 회사 기밀을 마구 올리는데, **기존 방화벽으로는 이 HTTPS 암호화 데이터가 어디로 새는지 볼 수 없는 비가시성 문제가 컸다.**

#### 한줄 요약

- 회사 밖 구글 드라이브나 노션 같은 클라우드를 쓸 때, 직원이 딴짓 못하게 감시하고 기밀문서 유출을 막는 클라우드 세관이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DLP (데이터 유출 방지)**: 문서 안에 주민등록번호, 설계 도면, "대외비" 마크 같은 게 있는지 내용물을 다 까서 체크하고 업로드를 차단하는 기술이다.
- **프록시 연동 / API 연동**: 프록시는 직원 PC랑 클라우드 사이에 서서 올리는 순간 낚아채는(실시간) 방식이고, API는 이미 올라간 파일 중에 공유 풀린 게 없나 뒷구멍으로 순찰 도는(사후) 방식이다.

</details>

- **섀도 IT 가시성 확보**: 누가, 언제, 어떤 듣보잡 클라우드에, 무슨 파일을 올렸는지 100% 까발리고 통제한다.
- **프록시와 API의 하이브리드**: 업로드하는 행위는 프록시로 실시간 방어하고, 이미 올라가서 방치된 자료는 API로 뒤져서 권한을 강제로 회수하는 투트랙 방어선을 친다.

#### 한줄 요약

- 직원들이 몰래 쓰는 클라우드를 찾아내고, 파일 올릴 땐 프록시로 막고, 올라간 건 API로 지워버린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **접근 중개기 (Access Broker)**: 사용자가 클라우드로 쏘는 패킷을 중간에서 낚아채서 체크를 위해 화물칸을 까보는 엔진이다.
- **클라우드 위험 카탈로그**: 세상에 존재하는 수만 개의 클라우드 앱(SaaS)에 대해 "MS오피스(안전), 중국산 웹하드(위험)" 식으로 등급을 매겨놓은 거대한 블랙리스트 DB다.

</details>

```text
[ CASB 클라우드 섀도 IT 통제 구조 ]

[ 1. 사용자 / 단말 ] ── (직원: 폰이나 PC로 개인 드롭박스에 도면 올려야지~)
      │
      ▼ (클라우드 업로드 시도)
[ 2. 접근 중개기 (Proxy / API) ] ── (잠깐! 화물칸 열어. 어디로 뭐 보내냐?)
      │
  ┌───┴───┐
  │       │ (위험도 체크 & DLP 검사)
[위험DB] [정책엔진] ── (카탈로그 조회: 저 웹하드 금지됨. 파일에 기밀 있음 $\to$ 컷트!)
  │       │
  └───┬───┘
      ▼ (정책 통과한 정상 트래픽만 허용)
[ 3. 클라우드 서비스 (SaaS) ] ── (회사 승인받은 구글 워크스페이스 등)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **사용자 / 단말** | 회사 몰래 개인 클라우드에 **기밀 데이터 빼돌리려는 섀도 IT의 주범** | Endpoint |
| **접근 중개기** | 사용자랑 클라우드 사이에 껴서 **패킷 가로채고 화물칸 감시하는 문지기** | Broker |
| **위험 카탈로그 DB** | 수만 개 SaaS 앱의 **보안 스펙과 위험도를 매겨놓은 블랙리스트** | Risk Catalog |
| **CASB 정책 엔진** | 문맥(Context) 보고 차단할지, 암호화할지, 냅둘지 **결정하는 뇌** | Policy Engine |
| **클라우드 서비스** | 결국 최종적으로 데이터가 저장되는 **외부 SaaS (구글 드라이브 등)** | Cloud (SaaS) |

#### 한줄 요약

- 사용자가 클라우드에 접속하면 $\to$ 위험한 앱인지 체크하고 $\to$ 훔친 자료인지 확인해서 $\to$ 컷트하거나 통과시킨다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **격리 및 공유 회수 (Quarantine / Revoke)**: 직원이 구글 드라이브에 올린 회사 기밀 문서를 실수로 외부인(Public) 누구나 볼 수 있게 링크를 풀어버렸을 때, CASB가 API로 순찰 돌다가 그 공유 링크를 부숴버리는 사후 무자비 조치다.

</details>

```text
[ CASB 클라우드 데이터 유출 방지 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [SaaS 사용 시도 및 트래픽 가로채기]
│ (직원: 개인 노트북으로 구글 드라이브에 파일 업로드 시도)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [서비스 위험 분류 (섀도 IT 색출)]
│ (CASB: 이거 회사 승인 앱 맞음? 위험 카탈로그 DB 조회)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [자료 및 행위 맥락 체크 (DLP)]
│ (CASB: 파일 열어봐. 어? 이 안에 회사 설계도면 있네?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [정책 조치 결정 (허용/차단/격리)]
│ (CASB: 민감 데이터 유출이다! 프록시 세션 즉각 차단!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [세션 집행 및 사후 공유 회수]
│ (실시간 업로드 막고, 이미 올라간 건 API로 링크 다 부숴버림)
└──────────────────────────────┘
```

### 동작 원리

1. 섀도 IT 색출 (위험 분류): 직원이 접속하려는 클라우드가 짱깨 웹하드인지 인가된 앱인지 카탈로그로 체크함.
2. 행위 맥락 검증 (DLP): 파일 외부 캡슐화 래퍼만 보는 게 아니라, 내용 까서 주민번호나 기밀 키워드 있는지 검사함.
3. 정책 조치 결정: 상황(Context)에 따라 단순 경고할지, 다운로드를 막을지, 세션을 끊을지 결정함.
4. 집행 및 격리: 위험하면 즉시 차단하고, 이미 클라우드에 저장된 과거 파일 중 퍼블릭으로 풀린 건 API로 강제 격리함.

#### 한줄 요약

- 무슨 앱 쓰는지 감시 $\to$ 무슨 파일인지 검사 $\to$ 기밀이면 실시간 차단 $\to$ 이미 올린 것도 링크 파괴.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **순방향 프록시 (Forward)**: 회사에서 나눠준 PC에 에이전트를 깔아서 나가는 트래픽을 다 잡아먹는 거다.
- **역방향 프록시 (Reverse)**: 직원이 자기 개인 폰이나 집 PC(BYOD)로 회사 구글 드라이브 로그인할 때, 입구에서 강제로 낚아채는 거다.
- **API 연동**: 실시간으로 트래픽을 가로채는 게 아니라, 클라우드 서버 뒷문(API)으로 들어가서 이미 저장된 파일들만 주기적으로 스캔하는 거다.

</details>

| CASB 연동 방식 비교 | **순방향 프록시 (Forward)** | **역방향 프록시 (Reverse)** | **API 연동 (API Integration)** |
|:---|:---|:---|:---|
| 핵심 특징 | **회사 PC에 감시앱 깔아서 폰트까지 감시함** | **회사 구글 드라이브 입구에 서서 출입증 검사함** | **주말에 빈 사무실 몰래 돌며 캐비닛 검사함** |
| 적용 타겟 단말 | **관리 단말 (회사 지급 PC)** | **비관리 단말 (직원 개인 폰, 집 PC 등 BYOD)** | **이미 클라우드에 저장된 과거 데이터** |
| 작동 원리 | PC에 깔린 에이전트가 나가는 트래픽 가로채서 실시간 차단 | SSO(통합로그인) 연동해서 회사 클라우드 들어올 때 프록시 태움 | 클라우드 서비스(SaaS) 관리자 API 호출해서 뒷구멍으로 감시 |
| 최고 장점 | 직원이 어떤 듣보잡 앱(미승인 클라우드)을 쓰는지 **100% 가시성 확보** | 에이전트 안 깔린 개인 폰으로 접속해도 **'다운로드 금지' 같은 통제 가능** | 실시간 트래픽 부하 안 먹고, **이미 외부에 유출된 공유 링크(Public) 컷트 가능** |
| 치명적 한계 | 직원 PC에 무조건 **감시 에이전트(Agent) 깔아야 해서 귀찮고 무거움** | 회사가 돈 주고 산(인가된) 클라우드 앱 입구만 막을 수 있음 | 실시간이 아니라 API 호출 주기(5분 등)마다 감시 텀이 생김 |

#### 한줄 요약

- 회사 PC는 순방향으로 다 막고, 개인 폰은 역방향으로 입구 컷트하고, 쌓인 데이터는 API로 순찰 돈다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **관리 / 비관리 단말 (Managed / Unmanaged)**: 회사에서 통제 앱 깔아준 사내 PC가 관리 단말, 집에서 굴러다니는 노트북이나 개인 폰이 비관리 단말이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 회사 PC로 몰래 **개인 웹하드에 도면 다 빼돌림** | 기존 방화벽은 HTTPS 443 암호화 포트 통신이라 내용물을 까보지 못함 | **순방향 프록시** 걸고 **DLP(유출 방지)** 켜서 도면 들어간 파일 업로드 즉시 원천 차단 | 섀도 IT를 통한 실시간 내부 데이터 외부 유출 원천 봉쇄 |
| 재택근무한다고 **개인 PC로 회사 클라우드 파일 싹 다운받음** | 비관리 단말(개인 PC)은 사내 에이전트가 안 깔려 있어서 통제할 방법이 없음 | **역방향 프록시** 걸어서 개인 PC 접속은 허용하되 **'다운로드/화면 캡처 금지'로 묶어버림** | BYOD 환경에서 통제 불능한 개인 기기에 회사 기밀 남는 홀 방어 |
| 실수로 구글 드라이브 링크를 **'전체 공개(Public)'로 풀어버림** | 한 번 올라간 파일은 실시간 프록시 통제를 벗어나 무방비 상태가 됨 | **API 연동** 돌려서 주기적으로 파일 권한 스캔하고, 퍼블릭 링크 보이면 **강제 '공유 회수' 때림** | 나도 모르게 구글링으로 외부에 털려 있는 좀비 데이터 사후 유출 컷트 |

#### 한줄 요약

- 올릴 땐 프록시(순방향)로 막고, 폰으로 다운받을 땐 역방향으로 막고, 실수로 전체 공개 누른 건 API로 거둬들여라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 무분별한 섀도 IT 사용과 SaaS 상의 데이터 유출을 방어하기 위해, **순/역방향 프록시(실시간 차단)** 와 **API 연동(사후 격리)** 을 짬뽕한 하이브리드 CASB 통제 기조 확립함

#### 한줄 요약

- CASB는 단순히 사이트 막는 방화벽이 아니라, 클라우드 시대에 회사 데이터가 어디로 날아가는지 추적하는 GPS 추적기이자 자동 폭파 장치다.
