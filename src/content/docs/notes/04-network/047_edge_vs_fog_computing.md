## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **엣지 컴퓨팅(Edge Computing)**: 데이터가 발생하는 최외곽 앤드포인트(센서/단말) 단에서 연산과 제어를 즉시 수행하는 분산 처리 기술이다.
- **포그 컴퓨팅(Fog Computing)**: 엣지 단말과 중앙 클라우드 사이의 중간 네트워크 계층(스위치/게이트웨이)에 포그 노드를 배치하여 다수 엣지 데이터를 집계, 필터링 및 조정하는 다계층 아키텍처이다.

</details>

- 정의/개념: **엣지 컴퓨팅**은 데이터 발생 현장 앤드포인트 단에서 직접 즉시 연산을 수행하는 방식이며, **포그 컴퓨팅**은 엣지 노드와 중앙 클라우드 사이의 중간 지역 게이트웨이 계층에서 다수 엣지의 데이터를 수집, 집계 및 지역 정책을 통합 조정하는 다계층(Multi-tier) 분산 컴퓨팅 기술이다.
- 배경/필요성: 수십억 개의 IoT 단말 데이터를 중앙 클라우드로 집중 전송할 때 발생하는 유선망 네트워크 과부하 및 전송 지연(100ms 이상)을 극복하고, 현장 초저지연 처리(Edge)와 지역 자원 최적화(Fog)를 역할 분담하기 위해 도입되었다.

#### 한줄 요약

- 데이터 발생 현장 직접 즉시 처리(Edge)와 중간 계층 수집 및 지역 정책 통합 조정(Fog)의 역할 분담을 통한 계층적 분산 컴퓨팅 아키텍처.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **조정 범위(Control & Orchestration Domain)**: 단일 연산 노드가 제어하고 데이터를 집계할 수 있는 기기 및 현장의 물리적/논리적 영역 범위이다.
- **장애 독립성(Fault Autonomy / Isolation)**: 상위 포그 노드나 중앙 클라우드가 마비되어도 엣지 노드가 현장의 필수 제어를 독립적으로 계속 구동하는 특성이다.

</details>

- **엣지 컴퓨팅 (앤드포인트 즉시 제어)**: 데이터 발생 단말에 결합되어 1ms~10ms 수준의 초저지연 반응을 제공하며 네트워크 연결이 단락되어도 독립 구동한다.
- **포그 컴퓨팅 (다계층 지역 집계 및 분산)**: LAN/MAN 상위 계층에 위치하여 복수 엣지 노드 간의 트래픽을 필터링 및 1차 중계하고 지역 정책을 자율 조정한다.
- **계층적 데이터 삭감 **: 엣지가 수집한 원시 데이터(Raw Data)를 1차 요약하여 포그 노드로 전달하고, 포그 노드가 분석용 통계 데이터만 중앙 클라우드로 수송하여 백홀 대역폭을 극적으로 절감한다.

#### 한줄 요약

- 엣지의 앤드포인트 단위 실시간 즉시 처리와 포그의 다계층 지역 자원 집계 및 공동 정책 제어로 효율성 분화.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **엣지 노드(Edge Node)**: 현장 센서/기계에 내장되거나 직결되어 데이터 수집 및 즉시 제어를 실행하는 앤드포인트 장치이다.
- **포그 노드(Fog Node)**: 엣지 노드 상위의 스위치, 라우터, 로컬 서버 형태로 존재하여 지역 트래픽을 집계하고 오케스트레이션을 수행하는 노드이다.

</details>

```text
계층적 분산 컴퓨팅 아키텍처 (Edge to Fog to Cloud)
├─ 중앙 처리 계층 (Central Cloud Layer - Global AI & Storage)
├─ 중간 집계 계층 (Fog Layer - Regional Gateways / Fog Nodes)
├─ 현장 처리 계층 (Edge Layer - Smart Sensors / Edge Devices)
└─ 실물 단말 계층 (Thing Layer - IoT Actuators & Sensors)
```

선의 의미: 실물 단말 계층의 데이터가 엣지 처리 계층에서 즉시 연산되고, 요약 정보가 중간 포그 계층으로 수집되어 정책이 조정된 후 중앙 클라우드로 대용량 저장되는 3계층 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 센서 및 액추에이터 (Things) | 무선/유선 인터페이스를 통해 산업 현장 물리 데이터 측정 및 제어 명령 직접 실행 |
| 엣지 노드 (Edge Node) | 단일 장비/센서 근접 연산, 원시 데이터 1차 필터링 및 1ms 대 신속 긴급 제어 명령 수행 |
| 포그 노드 (Fog Node) | 소구역(Area) 내 수십~수천 개 엣지 노드의 데이터를 집계, 필터링 및 지역 공유 자원 오케스트레이션 |
| 중앙 클라우드 (Central Cloud) | 포그 노드가 정제하여 송신한 데이터를 장기 보관하고 글로벌 AI/ML 분석 모델 학습 및 배포 |
| 통합 오케스트레이터 | 제어 기한(Latency) 및 노드 자원 상태에 따라 엣지-포그-클라우드 간 알고리즘 동적 분배 |

#### 한줄 요약

- 엣지는 즉시 제어, 포그는 지역 집계 후 클라우드 전달

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **원시 데이터(Raw Data)**: 센서가 측정한 정제되지 않은 연속 데이터로, 엣지 단에서 즉시 처리되거나 축약 대상이 된다.
- **요약 상태(Summarized State)**: 엣지 노드가 원시 데이터를 분석하여 상위 포그 노드로 수송하기 위해 축약한 핵심 지표 데이터이다.
- **지역 정책(Local Policy)**: 포그 노드가 구역 내 복수 엣지 노드의 동기화 및 협력을 위해 배포하는 지역 제어 지침이다.

</details>

```text
센서•단말 원시 데이터 생성
      │
      ├─ 실시간 긴급 제어 ───── 엣지 즉시 연산•액추에이터 제어
      │
      └─ 지역 집계 및 분석 ──── 필터링•요약 상태 생성
                                    │
                                    v
                              포그 노드: 지역 데이터 집계•자원 조정
                                    │
                                    ├─ 지역 제어 정책 하향 회신 ── 엣지 정책 적용
                                    │
                                    └─ 요약 데이터 수송 ──────── 중앙 클라우드 장기 분석
```

### 동작 원리

- **원시 데이터 생성**: 현장 측정값을 엣지에 전달
- **엣지 즉시 연산•액추에이터 제어**: 긴급 신호 처리
- **필터링•요약 상태 생성**: 상위 전송량 절감
- **포그 노드 지역 데이터 집계•자원 조정**: 지역 정책 수립
- **중앙 클라우드 장기 분석**: 장기 저장•모델 학습

#### 한줄 요약

- 원시 데이터 생성, 엣지의 즉시 긴급 제어, 포그 노드의 지역 단위 요약 집계 및 클라우드 빅데이터 전송 알고리즘.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **제어 기한(Control Latency Deadline)**: 시스템의 안전과 정상 동작을 위해 센서 측정부터 제어 출력까지 반드시 완료되어야 하는 최대 허용 시간 수치이다.

</details>

| 비교 항목 | **엣지 컴퓨팅 ** | **포그 컴퓨팅 ** | **중앙 클라우드 ** |
|:---|:---|:---|:---|
| 자원 배치 위치 | 데이터 발생 지점 (센서, 스마트 단말 내부) | 현장과 코어 사이 중간 지역 게이트웨이/서버 | 중앙 전용 IDC 데이터센터 |
| 반응 시간 | 1ms ~ 10ms 이내 (실시간 즉시 제어) | 10ms ~ 50ms 이내 (지역 준실시간 조정) | 100ms 이상 (비실시간 대규모 분석) |
| 처리 아키텍처 | 단일 현장 앤드포인트 중심 수평 구조 | 다계층(Multi-tier) 수직/수평 통합 아키텍처 | 중앙 집중형 고성능 클라우드 |
| 데이터 가공 | 원시 데이터(Raw Data) 즉시 처리 및 제어 | 원시 데이터 필터링, 축약 및 지역 집계 | 전사 데이터의 장기 저장 및 AI 학습 |
| 망 종속성 | 네트워킹 없이 오프라인 독립 동작 가능 | LAN/MAN 지역 네트워크 연결 필수 | WAN/백본 인프라 연결 및 유선망 필수 |

> 요약: 엣지는 단말 단의 실시간 처리, 포그는 중간 게이트웨이 단의 다계층 지역 데이터 집계, 클라우드는 전사 빅데이터 분석에 특화.

#### 한줄 요약

- 엣지는 단말 단의 실시간 처리, 포그는 중간 게이트웨이 단의 다계층 지역 데이터 집계, 클라우드는 전사 빅데이터 분석에 특화.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **이중화(Redundancy & High Availability)**: 특정 포그 노드의 고장이나 망 단락 시 예비 노드로 작업을 즉시 핸드오버하는 고가용성 설계이다.

</details>

| 문제점 | 발생 원인 | 실무 대응 대책 | 기대 효과 |
|:---|:---|:---|:---|
| 엣지-포그 간 자원 경합 | 엣지 처리량을 넘는 트래픽 | 제어 기한 기반 동적 **오프로딩** | 제어 기한 초과 완화 |
| 포그 노드 단일 장애(SPOF) | 중간 포그 게이트웨이 고장 시 하부 엣지 제어 마비 | 포그 노드 이중화(HA) 및 엣지 노드 독립 자율권 부여 | 포그 장애 시에도 엣지 노드의 현장 자율성 유지 |
| 데이터 동기화 오차 | 다계층 노드 간 데이터 수집 시간차 발생 | PTP(IEEE 1588) 기반 계층 간 정밀 시각 동기화 | 시계열 데이터 일관성 및 정밀 통계 확보 |
| 계층 간 보안 위협 | 오픈 포그 노드를 통한 인접 엣지 노드 해킹 | 노드 간 Mutual TLS 인증 및 Zero Trust 보안 적용 | 미승인 노드 접속 차단 및 안전한 데이터 유통 |

#### 한줄 요약

- 계층별 Latency Deadline 기반 자원 할당, 포그 노드 이중화(Redundancy) 및 엣지 노드 독립 자율 구동(Autonomy) 확보로 시스템 가용성 유지.

## Ⅶ. 결론

- 즉시 현장 제어는 **엣지**, 지역 집계•조정은 **포그** 선택

#### 한줄 요약

- 응답 지연 요구 조건 및 데이터 집계 범위에 맞춘 계층적 엣지-포그 통합 아키텍처 구현 필수.
