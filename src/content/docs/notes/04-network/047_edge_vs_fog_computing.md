## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **엣지 컴퓨팅(Edge Computing)**: 데이터 발생점 가까이에서 저장•연산•제어하는 구조
- **포그 컴퓨팅(Fog Computing)**: 다계층 지역 노드에서 데이터와 자원을 집계•조정하는 구조

</details>

- 정의/개념: 발생점에서 처리하는 **엣지**와 지역 노드에서 조정하는 **포그 구조**
- 배경/필요성: 중앙 클라우드 단독 처리로 **제어 기한 초과•백홀 과부하**

#### 한줄 요약

- 기계 바로 옆의 엣지가 급한 판단을 하고 지역 포그가 여러 기계의 정보를 모아 조정한다.

## Ⅱ. 특징

- **엣지** 의 발생점 처리가 실시간 판단•제어 지연 최소화
- **포그** 의 다수 엣지 집계가 지역 정책•자원 조정
- 처리 계층이 상위일수록 **지연 증가•조정 범위 확대**

#### 한줄 요약

- 같은 서버도 한 장비만 즉시 제어하면 엣지, 여러 현장을 모아 조정하면 포그 역할을 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **엣지 노드**: 단일 현장의 데이터 필터링•추론•즉시 제어를 수행하는 장치나 서버이다.
- **포그 노드**: 여러 엣지 노드의 데이터를 지역 단위로 집계하고 자원•정책을 조정하는 중간 노드이다.

</details>

```mermaid
block-beta
    columns 1
    block:CONTINUUM["분산 처리 계층"]
        columns 1
        DEVICE["장치•센서"]
        EDGE["엣지 노드"]
        FOG["포그 노드"]
        CLOUD["클라우드"]
        ORCH["오케스트레이터"]
    end
    DEVICE --- EDGE
    EDGE --- FOG
    FOG --- CLOUD
    ORCH --- EDGE
    ORCH --- FOG
    ORCH --- CLOUD
```

| 구성요소 | 책임 |
|:---|:---|
| 장치•센서 | 현장 **데이터 생성•제어 명령** 수행 |
| 엣지 노드 | 단일 현장의 **필터링•추론•제어** |
| 포그 노드 | 여러 엣지의 **지역 집계•자원 조정** |
| 클라우드 | 전사 데이터의 **장기 저장•모델 학습** |
| 오케스트레이터 | 기한•자원•장애에 따라 **작업 배치** |

#### 한줄 요약

- 현장 데이터는 위로 갈수록 요약되고 중앙 정책은 아래로 내려오며 급한 제어는 엣지에 남는다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **요약 상태**: 엣지가 원시 데이터에서 상위 지역 조정에 필요한 정보만 추려 만든 데이터이다.
- **지역 정책**: 포그가 여러 현장의 공동 자원과 동작을 조정하도록 엣지에 전달하는 규칙이다.

</details>

```mermaid
sequenceDiagram
    participant 센서•장치
    participant 엣지노드
    participant 포그노드
    participant 클라우드
    센서•장치->>엣지노드: 현장 데이터
    엣지노드-->>센서•장치: 제어 명령
    엣지노드->>포그노드: 1. 요약 상태
    포그노드->>엣지노드: 2. 지역 정책
    포그노드->>클라우드: 3. 집계 데이터
```

**동작 원리**

1. **요약 상태**: 엣지가 제어에 필요한 상태만 **포그 노드** 로 전송
2. **지역 정책**: 포그가 여러 현장의 **공동 자원•정책** 조정
3. **집계 데이터**: 포그가 장기 분석 대상을 **클라우드** 로 전송

#### 한줄 요약

- 센서와 가까운 곳에서 즉시 멈추고 여러 현장의 공통 판단만 위 계층으로 올린다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **원시 데이터**: 필터링•요약•집계를 거치지 않은 최초 수집 데이터이다.
- **조정 범위**: 하나의 실행 노드가 상태를 모으고 정책을 적용하는 장치•현장의 공간적 범위이다.

</details>

| 분산 처리 방식 | 엣지 컴퓨팅 | 포그 컴퓨팅 |
|:---|:---|:---|
| 적용 기준 | 짧은 제어 기한과 **원시 데이터 처리** 가 필요할 때 | 다수 엣지의 **공동 정책 조정** 이 필요할 때 |
| 핵심 특징 | 발생점 인접 **단일 현장 처리** | 다계층 **지역 집계•분산 처리** |
| 한계 | 제한된 자원•**개별 노드 관리** 부담 | 계층 동기화•**장애 전파** 위험 |

> 요약: 제어 기한과 조정 범위로 엣지•포그 선택

#### 한줄 요약

- 한 장비의 급한 판단은 엣지에, 여러 현장을 함께 보는 판단은 포그에 둔다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **장애 독립성**: 상위 계층과의 연결이 끊겨도 하위 계층이 필수 기능을 계속 수행하는 성질이다.
- **이중화**: 같은 기능을 맡는 예비 노드나 경로를 두어 장애 시 전환하는 설계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 제어를 상위 계층에 배치해 **기한 초과** | 제어 기한별 **최하위 실행 노드** 배치 | 장치 제어 응답 지연 감소 |
| 포그 장애로 다수 현장의 **정책 조정 중단** | 지역 **이중화•독립 운전** 모드 | 포그 장애의 현장 확산 범위 축소 |
| 원시 데이터 전송으로 **백홀 대역폭** 고갈 | 엣지 **필터•요약 기준** 설정 | 상위 계층 전송량 감소 |

#### 한줄 요약

- 즉시 대응할 제어는 설비 인접 엣지가 맡고 여러 공장의 데이터를 모을 업무는 지역 포그가 맡는다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **제어 기한**: 센서 입력을 받은 뒤 안전한 동작을 위해 제어 결과를 반드시 반환해야 하는 최대 시간이다.

</details>

- 짧은 제어 기한 작업은 **엣지**, 다수 현장 집계•정책 조정은 **포그** 배치

#### 한줄 요약

- 빨리 끝내야 할수록 아래 계층에, 넓게 모아 볼수록 위 계층에 작업을 둬야 한다.
