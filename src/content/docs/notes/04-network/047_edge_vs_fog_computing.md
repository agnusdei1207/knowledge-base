## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **엣지 컴퓨팅(Edge Computing)**: 스마트폰, CCTV, 공장 로봇 같은 기기 맨 끝단(현장)에서 데이터가 생기자마자 0.001초 만에 바로 연산하고 쳐내버리는 초말단 컴퓨팅이다.
- **포그 컴퓨팅(Fog Computing)**: 하늘에 있는 구름(클라우드)이 땅으로 내려와 안개(포그)가 된 것처럼, 동네 지역 라우터 수준에 서버를 둬서 엣지 데이터를 한 번 싹 쓸어 모아 정리하는 중간 관리자다.

</details>

- 정의: **엣지 컴퓨팅** 데이터 발생 현장 기기 안에서 즉시 연산을 끝내는 방식이고, **포그 컴퓨팅** 엣지와 중앙 클라우드 사이에 있는 '동네 게이트웨이'가 데이터를 모아 교통정리 하는 다계층 기술이다.
- 배경: 수십억 개 IoT 기기 데이터를 죄다 클라우드로 보내면 통신망이 발생하니까, 제일 급한 건 현장(엣지)에서 바로 쳐내고, 동네 트래픽은 동네 스위치(포그)에서 묶어 짬 처리하려고 도입함.

#### 한줄 요약

- 급한 건 현장(Edge)에서 바로 처리하고, 통계랑 요약은 동네 반장(Fog)이 모아서 클라우드 본사로 보내는 계층 분업 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **장애 독립성(Fault Autonomy)**: 통신사 망이 끊기거나 중앙 클라우드에 불이 나도, 현장 기계(엣지)는 "알빠노" 하면서 자기 혼자서 계속 공장을 돌리는 생존 본능이다.

</details>

- **엣지 컴퓨팅 (말단 즉결 심판)**: 기계에 찰싹 달라붙어 있어서 인터넷 선이 뽑혀도(오프라인) 독고다이로 1ms 만에 긴급 브레이크를 밟는 등 즉시 제어를 수행함.
- **포그 컴퓨팅 (동네 반장 역할)**: 공유기나 지역 게이트웨이에 살면서 여러 엣지 기기들의 데이터를 싹 수집하고, 쓸데없는 쓰레기 데이터는 버리고 알맹이만 걸러냄.
- **계층적 데이터 싹둑 (데이터 다이어트)**: 엣지가 1차 요약 $\to$ 포그가 2차 요약 $\to$ 중앙 클라우드로는 꼭 필요한 통계만 보내서 백홀 인터넷 요금과 트래픽을 아낌.

#### 한줄 요약

- 엣지는 인터넷 끊겨도 혼자 살아남는 즉각 행동대장이고, 포그는 여러 엣지를 묶어서 데이터 다이어트 시키는 동네 관리자다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포그 노드(Fog Node)**: 단순한 인터넷 공유기가 아니라, 그 안에 조그만 서버를 달아놓고 동네 엣지 기기 100대의 데이터를 모아서 분석하는 골목대장 컴퓨터다.

</details>

```text
[ 계층적 분산 컴퓨팅 직관적 비교 구조 ]

[ 클라우드 ] ─── (지구 전체 관리, 딥러닝 뇌)
      ▲
      │ (요약본만 찔끔 보냄)
[ 포그 노드 ] ── (동네 반장, 지역 게이트웨이)
  ▲      ▲
  │      │ (원시 데이터 1차 요약)
[ 엣지 ] [ 엣지 ] (말단 행동대장, CCTV/스마트워치)
  │      │
[ 센서 ] [ 로봇 ] (현장 수작업 반복 기계)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **센서/단말기 (Things)** | 현장에서 땀 흘리며 **데이터를 무식하게 퍼올리는 수작업 반복 기계들** | IoT 단말 |
| **엣지 노드 (Edge)** | 기계 바로 옆에서 대기 타다가 **0.001초 만에 브레이크 밟는 행동대장** | 현장 기기 내장 |
| **포그 노드 (Fog)** | 행동대장들 데이터 모아서 **쓰레기는 버리고 요약본만 챙기는 동네 반장** | 지역 스위치/공유기 |
| **중앙 클라우드 (Cloud)**| 포그가 보낸 요약본만 받아 **빅데이터 딥러닝 돌리는 본사 회장님** | 중앙 데이터센터 |

#### 한줄 요약

- 수작업 반복 기계(센서) $\to$ 행동대장(엣지) $\to$ 동네 반장(포그) $\to$ 회장님(클라우드)으로 이어지는 철저한 계층 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **원시 데이터(Raw Data)**: 센서가 1초에 1,000번씩 찍어내는, 쓸데없는 게 99%인 가공되지 않은 날것의 쓰레기 더미 데이터다. 이걸 다 클라우드에 보내면 통신망이 터진다.

</details>

```text
[ 엣지 $\to$ 포그 $\to$ 클라우드 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [원시 데이터 쓰나미 폭발] │
│ (센서: 온도 100도! 100도! 100도!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [엣지 노드 긴급 즉결 심판]│
│ (엣지: 100도 넘었네 당장 기계 멈춰!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [포그 노드 동네 데이터 짬 처리]
│ (포그: 100도 데이터 만 개 지우고 '이상함' 요약)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [클라우드 보고 및 빅데이터 학습]
│ (본사: 요약본 보니 고장 잦네, AI 수정해)
└──────────────────────────────┘
```

### 동작 원리

1. 원시 데이터 생성: 센서가 쓸모없는 쓰레기 데이터를 포함해 엄청난 양을 쏟아냄.
2. 엣지 즉각 제어: 엣지가 1ms 만에 사고 날 것 같은 긴급 데이터를 처리하고 액추에이터(기계)를 멈춤.
3. 포그 요약 집계: 동네 포그 노드가 엣지들한테 받은 수만 개 데이터를 필터링하고 요약본을 생성함.
4. 클라우드 전송: 포그가 정제한 엑기스 데이터만 중앙 클라우드로 보내 대규모 AI 모델을 학습시킴.

#### 한줄 요약

- 엣지는 바로 브레이크 밟고, 포그는 쓸데없는 데이터를 지워 통신비를 아끼고, 클라우드는 엑기스로 딥러닝 돌린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

| 구분 | **엣지 컴퓨팅** | **포그 컴퓨팅** | **중앙 클라우드** |
|:---|:---|:---|:---|
| 핵심 특징 | 현장에서 즉결 심판하는 **행동대장** | 동네 관리소 **반장님** | 서울 본사 **회장님** |
| 자원 위치 | 센서 옆, **스마트폰/CCTV 내부** | **지역 라우터, 동네 공유기** | **미국/서울 대형 IDC** |
| 핑 (반응 속도) | 1ms ~ 10ms 이내 **(빛의 속도)** | 10ms ~ 50ms 이내 **(살짝 느림)** | 100ms 이상 **(속 터짐)** |
| 데이터 처리 방식 | **쓰레기 원시 데이터** 즉시 짬 처리 | 여러 엣지 모아서 **요약 짬 처리** | 엑기스만 모아서 **장기 딥러닝** |
| 망 단절(오프라인)| **알빠노 (지 혼자 알아서 계속 돌아감)** | 인터넷 안 되면 좀 곤란함 | 인터넷 끊기면 **바보 깡통 됨** |

#### 한줄 요약

- 엣지는 존나 빠르지만 시야가 좁고, 클라우드는 똑똑하지만 핑이 길며, 포그는 그 둘 사이를 중재하는 허리 역할이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SPOF(단일 장애점, Single Point of Failure)**: 동네 포그 노드(공유기) 하나 뻗었는데, 밑에 달린 엣지 기기 수백 대가 다 같이 바보가 되는 최악의 약점이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 엣지가 감당 못 할 만큼 **데이터가 쏟아져서 터짐** | 엣지 노드는 조그마해서 CPU 깡성능이 매우 딸림 | 무거운 연산은 포그나 클라우드로 패스하는 **동적 오프로딩** | 엣지 CPU 발생하는 거 방어 및 다운타임 방지 |
| 포그 노드 뻗으니까 **밑에 엣지들도 다 같이 죽음** | 포그 노드 하나에 엣지들이 너무 의존하는 **SPOF 발생** | 포그 뻗어도 엣지가 알아서 굴러가게 **장애 독립성(Autonomy) 확보** | 동네 공유기 터져도 공장 로봇은 안 멈추고 돌아감 |
| 엣지끼리 시간 안 맞아서 **통계 순서가 개판 남** | 엣지랑 포그 간 전송 핑 차이 땜에 시간이 꼬임 | PTP(IEEE 1588) 돌려서 **수천 개 노드 시간 0.001초 단위로 맞춤** | 시계열 데이터 꼬이는 거 막고 분석 퀄리티 보장 |
| 동네 길바닥 포그 노드라 **해커가 랜선 꽂고 털어감** | 클라우드(데이터센터)보다 물리적 보안이 존나게 취약함 | 노드끼리 **상호 인증(mTLS) 빡세게 돌리고 제로 트러스트 도입** | 미승인 깡통 해킹 기계 접속 원천 차단 |

#### 한줄 요약

- 엣지 CPU 터질 거 같으면 위로 던지고(오프로딩), 위쪽 뻗어도 엣지는 살게 독립성 부여하고, 털릴 거 대비해 빡세게 인증해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 데이터 폭증에 따른 클라우드 병목을 해소하기 위해, 앤드포인트 즉결 심판은 **Edge**, 지역 자원 집계와 요약 다이어트는 **Fog** 기반 다계층 분산 처리하는 **Edge-Fog-Cloud** 아키텍처 기조 확립함

#### 한줄 요약

- 클라우드 하나로 세상 모든 데이터를 감당하려던 무식한 시절은 끝났다. 엣지와 포그가 데이터를 썰고 요약해 줘야 클라우드가 뇌출혈 안 걸린다.
