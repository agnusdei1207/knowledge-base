## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스푸핑 (Spoofing)**: 해커가 내 번호를 은행 번호로 위조하거나(IP), 내 이름을 서버 이름으로 속여서(DNS) 통신을 중간에서 가로채거나 엉뚱한 곳으로 보내버리는 신분 위조 사기다.

</details>

- 정의: **스푸핑** **ARP(MAC)**, **IP**, **DNS(도메인)** 계층에서 장비들이 신뢰하는 식별자(주소/이름)를 교묘하게 위조해, 통신 경로를 탈취하거나 피해자를 가짜 서버로 낚는 네트워크 기만 공격이다.
- 배경: 초창기 네트워크 프로토콜(TCP/IP)은 "보낸 사람이 진짜 그 사람 맞냐?"를 체크하는 인증 기능 없이 성선설 기반으로 만들어져서, **주소만 위조해서 보내면 장비들이 바보같이 다 믿어버렸다.** #### 한줄 요약

- 발신자 번호를 조작해서 보이스피싱을 하듯, 네트워크 주소를 위조해서 통신을 엿듣거나 가짜 사이트로 낚는 공격이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **계층 검증 (Layer Validation)**: 편지 봉투의 발신자(IP), 편지 내용의 서명(DNS) 등 각 네트워크 계층마다 위조 여부를 체크하는 방어 기술이다.
- **캐시 오염 (Cache Poisoning)**: 컴퓨터나 스위치가 해커가 쏜 "네이버 주소는 1.1.1.1이야"라는 가짜 정보를 자기 단기 기억력(캐시)에 저장해버려서, 해커가 떠나도 계속 피싱 사이트로 접속되는 상태이상이다.

</details>

- **체크 (계층별 검증)**: 주소가 진짜인지 가짜인지 MAC 매핑, 라우팅 역경로, 전자서명(DNSSEC)으로 계층마다 교차 검증을 때린다.
- **기억력 마비 (캐시 오염)**: 공격을 차단해도 이미 메모리(캐시)에 가짜 주소가 독처럼 퍼져있으면 피해가 지속되므로 반드시 치료(플러시)가 필요하다.

#### 한줄 요약

- 주소를 위조하는 공격이므로 들어올 때 체크로 막아야 하고, 이미 털렸으면 머릿속(캐시)에 남은 헛소리를 지워야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **신뢰 정보원 (Trust Anchor)**: 주소 바인딩, 라우팅 경로, 전자서명 등 수신 식별자의 진위를 판정할 '팩트'를 제공하는 원천 DB다.
- **종단 인증 (End-to-End Auth)**: 스푸핑으로 길을 잘못 들어서 해커 서버에 도착했더라도, 인증서(TLS) 까보라고 해서 가짜 서버인 걸 한 번 더 잡아내는 최종 방어선이다.

</details>

```text
[ 스푸핑 공격 및 체크 방어 구조 ]

[ 1. 신뢰 정보원 ] ── (진짜 IP-MAC 짝꿍, 진짜 도메인 서명 갖고 있는 원본 DB)
      │
      ▼
[ 2. 계층 검증기 (라우터/스위치/방화벽) ] ── (해커가 보낸 가짜 주소인지 체크함)
      │
      ▼ (스푸핑 뚫리고 가짜 서버에 도착했을 경우 대비)
[ 3. 종단 인증기 (TLS/인증서) ] ── (너 진짜 네이버 맞아? 신분증(인증서) 까봐!)
      │
      ▼
[ 4. 대응•복구기 ] ── (해커 포트 차단하고 오염된 캐시 싹 다 날림)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **신뢰 정보원** | "이 주소가 진짜다"라고 **팩트를 제공하는 기준 데이터** | Trust DB |
| **계층 검증기** | 들어온 주소랑 DB랑 비교해서 **위조된 놈 컷트하는 문지기** | Verifier |
| **종단 인증기** | 목적지 도착해서 **진짜 서버 맞는지 인증서로 한 번 더 검증하는 보안관** | TLS Auth |
| **대응•복구기** | 해커 차단하고 장비에 **독(오염된 캐시) 퍼진 거 싹 다 지우는 치료사** | Remediation |

#### 한줄 요약

- DB랑 비교해서 입구 컷트하고, 통과했어도 도착지에서 민증(인증서) 검사 한 번 더 하고, 해커 흔적(캐시)은 싹 지운다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **위조 출처 차단 / 오염 상태 복구**: 가짜 패킷을 폐기하는 걸 넘어 공격자가 붙은 포트를 차단하고, 이미 속아서 저장한 가짜 기억(캐시)을 삭제하는 사후 처리다.

</details>

```text
[ 스푸핑 체크 및 캐시 정화 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [신뢰 기준 조회 및 패킷 수신]
│ (장비: 패킷 들어왔네? 진짜 주소 맞나 DB 조회해 봐)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [위조 체크 (바인딩/서명)]
│ (장비: 어? 이 MAC 주소 아까 걔 아닌데? 위조 발견!)
│ (일치하면 $\to$ 종단 신원 인증(TLS)으로 넘어감)
└──────────────┬───────────────┘
               ▼ (불일치 시)
┌──────────────────────────────┐
│ 3. [위조 출처 즉각 차단]     │
│ (스위치: 해커 포트(Port) 내려버리고 통신 컷트함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [오염 상태 복구 (캐시 삭제)]
│ (PC/스위치: 방금 해커가 쏜 가짜 주소표 캐시에서 싹 다 지워라!)
└──────────────────────────────┘
```

### 동작 원리

1. 신뢰 기준 조회: 패킷이 들어오면 공유기나 라우터가 자기가 갖고 있는 진짜 주소록(바인딩/경로/서명)을 꺼냄.
2. 위조 체크: 주소가 안 맞으면 위조로 판정하고, 맞으면 통과시킨 뒤 목적지에서 진짜 서버인지 인증서(TLS)로 재확인.
3. 위조 출처 차단: 가짜로 판명되면 패킷을 바로 휴지통에 처박고 해커가 붙어있는 물리 포트를 막아버림.
4. 오염 상태 복구: 찰나의 순간에 장비들이 낚여서 저장해 버린 가짜 MAC이나 IP를 캐시에서 날려버림.

#### 한줄 요약

- "진짜 주소 맞아?" 체크하고 $\to$ 구라치면 쫓아낸 뒤 $\to$ 뇌 속에 남은 거짓말(캐시)까지 세척하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ARP 스푸핑**: 같은 사무실 네트워크(LAN) 안에서 내 MAC 주소를 공유기 MAC 주소라고 속여서 남의 통신을 가로채는 짓거리다.
- **IP 스푸핑**: 출발지 IP를 다른 사람 IP로 위조해서, 서버가 반사하는 응답 패킷을 그 사람한테 쏟아지게 만드는(디도스) 공격이다.
- **DNS 스푸핑**: "네이버 주소는 여기야"라고 가짜 IP를 알려줘서 피싱 사이트로 유도하는 짓이다.

</details>

| 스푸핑 종류 비교 | **ARP 스푸핑 (MAC 위조)** | **IP 스푸핑 (IP 위조)** | **DNS 스푸핑 (도메인 위조)** |
|:---|:---|:---|:---|
| 핵심 특징 | **같은 사무실 직원이 부장님 행세함** | **남의 주민번호로 폭탄 우편물 보냄** | **네이버 쳤는데 해커 사이트로 낚임** |
| 공격 타겟 위치 | 같은 사무실/네트워크 (근거리망 LAN) | 외부망 (라우터 건너편 어딘가) | 사용자 PC나 라우터의 DNS 캐시 메모리 |
| 핵심 목적 | 중간에서 **통신 가로채서 엿듣기 (중간자 공격, MITM)** | 나를 숨기고 공격하거나, **남의 주소로 튕겨내서 타격(반사 공격 디도스)** | 가짜 피싱 사이트로 유도해서 **ID/PW 털기** |
| 치명적 한계 | 라우터(공유기) 밖으로 못 나감 (로컬 한정) | 응답 패킷은 남이 받아서 내가 엿듣진 못함 | 한번 침해당하면 캐시 지울 때까지 평생 낚임 |

#### 한줄 요약

- 같은 사무실 엿듣기는 ARP, 신분 세탁해서 폭탄 튕겨내기는 IP, 가짜 사이트로 낚시는 DNS 스푸핑이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DAI (동적 ARP 검사)**: 스위치가 스푸핑 막으려고 공유기(DHCP)한테 진짜 IP-MAC 짝꿍 목록을 받아둔 다음, 헛소리하는 놈 포트를 컷트하는 방어 기술이다.
- **uRPF (역경로 전달)**: 라우터가 "출발지 IP가 1.1.1.1이라는데, 1.1.1.1 방향에서 온 게 맞나?" 하고 역으로 체크해서 방향이 다르면(가짜면) 버리는 기능이다.
- **DNSSEC (DNS 보안 확장)**: "이게 진짜 네이버 IP다"라고 DNS 서버가 전자서명 도장을 찍어줘서 위조를 원천 차단하는 보안 확장팩이다.
- **BCP 38**: 방화벽이나 라우터 입구에서 사설 IP나 말도 안 되는 위조 출발지 IP를 애초에 걸러버리는 기본 룰이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 해커가 공유기인 척 **사내 통신 다 엿들음 (ARP)** | 해커가 가짜 MAC 주소 뿌렸는데, PC랑 스위치가 바보같이 믿음 | 스위치에 **DAI(동적 ARP 검사) 걸어서, 가짜 짝꿍 정보 뿌리는 포트를 막아버림** | 내부망 중간자 공격(MITM) 및 도청 원천 차단 |
| 남의 IP로 위조해서 **가짜 트래픽 폭탄 쏨 (IP 반사 공격)** | 라우터가 출발지 IP 진짜인지 확인 안 하고 무지성으로 통과시킴 | 라우터 입구에서 **uRPF 켜고, BCP 38 룰 씌워서 방향 안 맞는 가짜 출발지 패킷 다 버림** | 내 장비가 디도스 공격(DDoS) 경유지로 악용되는 거 차단 |
| 은행 쳤는데 **가짜 은행 떠서 비밀번호 털림 (DNS)** | DNS 서버가 해커한테 속아서 기억력(캐시)에 가짜 IP를 덮어씀 (오염) | DNS에 **DNSSEC (전자서명) 적용해서 위조 차단하고, 털렸으면 캐시(Flushdns) 싹 비움** | 파밍/피싱 사이트 낚임 방지 및 인증 신뢰성 100% 확보 |

#### 한줄 요약

- ARP는 스위치에서 DAI로 거르고, IP는 라우터에서 역추적(uRPF)으로 조지고, DNS는 서명(DNSSEC)으로 체크해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 네트워크 식별자 기만 공격을 방어하기 위해 **ARP는 DAI**, **IP는 uRPF와 BCP 38**, **DNS는 DNSSEC** 활용 적용하여 각 계층별 체크와 오염 복구를 수행하는 기조 확립함

#### 한줄 요약

- 스푸핑 방어는 그냥 백신 까는 게 아니라, 해커가 장난치는 네트워크 계층(L2/L3/L7)마다 각기 다른 검문소를 세워야 막힌다.
