## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IIoT (산업용 사물 인터넷)**: 집에서 불 끄는 수준이 아니라, 공장 기계, 발전소, 비행기 엔진 같은 무시무시한 산업 설비를 인터넷에 물려서 AI로 고장을 예측하고 원격 제어하는 거대한 산업용 핏줄이다.
- **IT (정보 기술) / OT (운영 기술)**: IT는 사무실에서 엑셀 돌리고 빅데이터 분석하는 화이트칼라 기술이고, OT는 공장 현장에서 모터 돌리고 밸브 잠그는 블루칼라 기술이다. IIoT는 이 둘을 억지로 결혼시키는 거다.

</details>

- 정의: **IIoT**는 현장의 쇳덩어리 설비 데이터(OT)를 끄집어내어 클라우드(IT)의 빅데이터/AI 분석과 연결해, 예지 정비와 공정 최적화를 때리는 융합 산업 운영 체계다.
- 배경: 옛날엔 사무실 망(IT)이랑 공장 망(OT)을 바로 꽂아버리면 해킹당했을 때 공장 폭발할 수도 있고, **클라우드에서 내린 늦은 명령에 기계가 오작동하니까 이 둘을 안전하게 잇는 체계가 필요했다.**

#### 한줄 요약

- 공장의 구닥다리 기계들한테 인터넷을 달아줘서, 본사 AI가 분석하고 원격으로 똑똑하게 공장을 돌리는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **현장 검증 (Field Validation)**: 서울 본사(IT)에서 "공장 펌프 압력 올려!" 하고 명령이 와도, 현장(OT) 기계가 "지금 올리면 파이프 터지는데?" 하고 판단해서 명령을 씹어버리는(재검증) 생명선 안전장치다.
- **DMZ (비무장 지대)**: IT 망과 OT 망이 쌩얼로 직접 만나지 못하게 중간에 벽을 치고 문지기(방화벽)를 세워서, 해커나 악성코드가 공장으로 바로 못 넘어가게 막는 완충 구역이다.

</details>

- **IT-OT 망 분리 (DMZ)**: 사무실 엑셀 파일 랜섬웨어가 공장 로봇으로 안 번지게, IT망과 OT망 사이에 절대 직접 통신을 불허하고 무조건 DMZ를 거쳐서 데이터를 릴레이 한다.
- **현장 최우선주의 (안전 재검증)**: 본사 클라우드 AI 분석이 아무리 뛰어나도, 최종 실행 직전에는 무조건 현장 기계(PLC)의 최신 안전 조건을 한 번 더 팩트 체크한다.
- **무결성 > 기밀성**: 일반 IT는 데이터 안 뺏기는(기밀성) 게 최고지만, IIoT(OT)는 센서값이 안 변조되고(무결성), 기계가 1초도 안 멈추는 것(가용성)이 목숨보다 중요하다.

#### 한줄 요약

- 본사랑 공장망을 직접 잇지 않고 방어벽을 치며, 본사 지시가 내려와도 위험하면 현장 기계가 알아서 씹는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PLC (프로그래머블 논리 제어기)**: 공장 컨베이어 벨트나 모터를 0.001초 단위로 끄고 켜는, 현장에서 직접 불꽃 튀기며 뛰는 두뇌(제어기)다.
- **SCADA (감시 제어 및 데이터 수집)**: 공장 전체 기계 상황을 모니터에 띄워주고 관리자가 마우스로 펌프를 껐다 켰다 할 수 있게 해주는 관제 시스템이다.
- **OT DMZ**: IT와 OT 망을 가르는 보안 구역으로, 데이터를 넘겨줄 프록시/히스토리안 서버만 딱 놔두는 철책선이다.

</details>

```text
[ IIoT IT/OT 융합 팩트 폭행 구조 ]

[ 1. IT 분석 / 업무 시스템 (Cloud/ERP) ] ── (AI 돌려서 "모터 곧 고장난다" 분석함)
      │
      ▼ (망 분리 철책선)
[ 2. OT DMZ (보안 완충 구역) ] ── (해커 컷트! 데이터만 프록시로 넘겨줌)
      │
      ▼
[ 3. 게이트웨이 / 엣지 (Edge) ] ── (구형 기계 데이터 싹 긁어모아서 번역함)
      │
      ▼
[ 4. PLC / SCADA (현장 관제) ] ── (실제 공장 돌리고 모니터링하는 현장 소장)
      │
      ▼
[ 5. 센서 / 액추에이터 / 안전 연동 ] ── (직접 현장에서 일하는 노가다 장비들)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **IT 분석 시스템** | 현장 데이터 긁어모아서 **빅데이터 분석하고 "이렇게 해라" 훈수 둠** | IT / Cloud |
| **OT DMZ** | 사무실 악성코드 안 넘어가게 **중간에서 멱살 잡고 컷트하는 방화벽 지대** | Security Zone |
| **게이트웨이 / 엣지**| 구닥다리 기계 데이터 **최신 규격으로 번역하고 통신 끊겨도 자체 제어함** | Edge |
| **PLC / SCADA** | 현장에서 **기계 직접 0.1초 단위로 조종하고(PLC), 모니터 띄워서 감시함(SCADA)** | OT Control |
| **센서 / 액추에이터**| 온도 재고, 밸브 열고, **폭발할 것 같으면 무조건 셧다운(안전 연동) 때림** | Field Device |

#### 한줄 요약

- 본사가 분석하고 $\to$ DMZ가 검열하고 $\to$ 게이트웨이가 번역하면 $\to$ 현장 PLC가 안전한지 따져보고 모터를 돌린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **안전 조건 재검증**: 본사 명령을 실행하기 직전에 최신 설비 상태와 허용 범위(압력, 온도 한계치)를 다시 확인해서 목숨 거는 팩트 체크 과정이다.

</details>

```text
[ IIoT 데이터 수집 및 현장 제어 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [공정 데이터 수집 및 정제]│
│ (현장: 센서값 긁어모아 쓰레기 데이터 지우고 DMZ로 넘김)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [클라우드/IT 조치 권고]   │
│ (IT: AI 분석 결과, 1번 모터 과열 예상됨. 속도 당장 줄여!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [운영자 승인 및 제어 명령]│
│ (SCADA: 오케이, 속도 줄이는 명령 하달)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [현장 안전 조건 재검증]   │
│ (PLC: 지금 속도 줄이면 공정 멈추는데? 팩트 체크 돌림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [제한 명령 실행 or 안전 차단]
│ (PLC: 안전 컷트! IT 명령 씹고 현장 유지 (Safety Interlock))
└──────────────────────────────┘
```

### 동작 원리

1. 데이터 수집/정제: 현장 센서에서 올라오는 잡음 섞인 데이터를 깨끗하게 정제(Filtering)해서 본사로 올림.
2. 조치 권고: 본사 IT 시스템(AI)이 데이터를 씹고 뜯어서 "베어링 수명 3일 남음. 교체해"라고 권고함.
3. 제어 한도 설정: 사람이 화면 보고 승인해서 실제 제어 명령을 현장으로 내려보냄.
4. 현장 안전 재검증: PLC가 명령 받자마자 "지금 돌리면 파이프 터지나?" 하고 0.1초 만에 안전 조건을 재검증함.
5. 명령 실행/차단: 안전하면 돌리고, 위험하면 상위 명령 개무시하고 기계 멈추거나 동작을 차단함.

#### 한줄 요약

- 데이터 올려서 훈수 받고 $\to$ 내린 명령이 안전한지 현장에서 팩트 체크하고 $\to$ 까딱하면 씹어버리는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소비자 IoT (Consumer IoT)**: 스마트 전구, 로봇 청소기, 홈캠 같이 집에서 쓰는 장난감 수준의 편리한 사물인터넷이다.

</details>

| 사물 인터넷 환경 | **IIoT (공장/발전소 등 산업용)** | **소비자 IoT (가정용 스마트홈)** |
|:---|:---|:---|
| 팩트 폭행 비유 | **한 번 실수하면 사람 죽고 공장 날아감** | **보일러 안 켜지면 쫌 춥고 맘** |
| 치명적 타격 | 중단/오동작 시 **수십억 손해 및 인명 피해 발생 (안전 1순위)** | 인터넷 끊기면 **재부팅하거나 스위치 수동으로 켜면 그만** |
| 통신 환경 및 수명 | 기계 수명 최소 20년, **영하 20도~영상 100도 혹독한 개고생 환경** | 기기 수명 짧고, 쾌적한 거실 빵빵한 와이파이 환경 |
| 구조적 특징 | **현장(OT) 제어와 본사(IT) 분석을 철저히 쪼개버림 (망 분리 필수)** | 휴대폰 앱이랑 스마트 전구가 클라우드로 쌩얼 다이렉트 연결 |

#### 한줄 요약

- 재부팅하면 끝인 장난감 IoT와 달리, IIoT는 재부팅하면 수백억 날아가서 무조건 안전과 무중단이 생명이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상태 노후화 (State Staleness)**: 1시 정각에 측정한 온도를 본사(IT)에서 한참 분석하고 1시 5분에 "온도 높으니까 당장 낮춰!"라고 뒷북 명령을 내렸는데, 이미 공장(OT)은 1시 2분에 알아서 식혀놔서 오히려 기계를 얼려버리는 뒷북 에러다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 사무실 랜섬웨어 걸렸는데 **공장 로봇이 다 멈춰버림 (장애 전파)** | 본사 IT 망이랑 공장 OT 망을 랜선 하나로 뻥 뚫어놔서 바이러스가 직행함 | 중간에 **OT DMZ 세우고 망 싹 다 분리(Purdue 모델 구역화)시킴** | 해킹 직통 경로 칼같이 썰어버리고 공장 안전 방어 |
| 본사 지시대로 밸브 닫았는데 **압력 터져서 공장 폭발할 뻔함** | 분석 딜레이 때문에 과거 데이터 기준으로 엉뚱한 뒷북(상태 노후화) 명령이 내려옴 | 명령 내려와도 절대 맹신 말고, **실행 0.1초 전에 PLC가 현장 상태 재검증해서 씹어버리게 코딩함** | 뒷북 오제어로 인한 끔찍한 물리적 대형사고 차단 |
| 보안 패치 쏜다고 핑(Ping) 날렸더니 **기계가 뻗어버림** | 20년 된 윈도우 95 기반 구닥다리 제어기가 해킹/패치 포트 스캔 부하를 못 버팀 | 능동 스캔(Ping) 절대 쏘지 말고, **스위치 포트 미러링으로 지나가는 패킷만 조용히 수동 관찰함** | 생산 라인 셧다운 안 시키고 투명하게 해킹 감시/대응 |

#### 한줄 요약

- 망 철저히 쪼개고, 본사 명령 무조건 믿지 말고 기계가 한 번 더 확인하게 만들며, 구형 장비는 조심해서 다뤄라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **안전 연동 차단 (Safety Interlock)**: 본사에서 내려온 승인된 명령이라도, 현장 센서값이 임계치를 넘는 등 최신 안전 조건을 위반하면 상위 제어 명령을 가차 없이 무시하고 실행을 막는 기계적인 방어막이다.

</details>

- 본사(IT)의 고도화된 빅데이터 분석과 현장(OT)의 실시간 제어 기술을 융합하되, **DMZ 망 분리**와 **현장 최우선 안전 연동(Interlock)** 기조 확립함

#### 한줄 요약

- IIoT는 멍청한 쇳덩어리에 AI의 두뇌를 달아주는 혁신이지만, AI가 미쳤을 때 현장에서 플러그를 뽑을 수 있는 안전장치가 목숨보다 중요하다.
