## 미리 알고가기

- **개방형 최단 경로 우선 OSPF(오에스피에프, Open Shortest Path First)**: 영어 네 낱말의 첫 글자를 쓴 표기로 링크 상태를 공유하고 각 라우터가 최단 경로를 계산하는 내부 라우팅 프로토콜
- **OSPF 버전 3(OSPF version 3, OSPFv3)**: '오에스피에프 브이 쓰리'로 읽고 버전(version)의 v와 판 번호 3을 붙여 IPv6 주소와 링크 단위 인접 관계를 지원하는 확장판임을 표시
- **인터넷 프로토콜 버전 6(Internet Protocol version 6, IPv6)**: 128비트 주소로 패킷을 전달하는 인터넷 프로토콜
- **링크 상태 광고(Link-State Advertisement, LSA)**: 라우터·네트워크·프리픽스의 연결 상태와 비용을 알리는 OSPF 정보 단위
- **링크 상태 데이터베이스(Link-State Database, LSDB)**: 같은 영역의 라우터들이 LSA를 동기화해 보유하는 공통 토폴로지 정보
- **최단 경로 우선(Shortest Path First, SPF)**: LSDB의 링크 비용으로 자신을 루트로 한 최단 경로 트리를 계산하는 알고리즘
- **영역(Area)**: LSA 플러딩과 SPF 계산 범위를 제한하는 OSPF 관리 구역
- **내부 게이트웨이 프로토콜(Interior Gateway Protocol, IGP)**: 하나의 자율 시스템 내부에서 경로를 교환하는 라우팅 프로토콜
- **인접 관계(Adjacency)**: OSPF 라우터가 헬로 조건을 확인하고 LSDB를 교환할 수 있도록 맺는 관계
- **플러딩(Flooding)**: 새 LSA를 같은 영역의 모든 OSPF 라우터에 전달해 LSDB를 동기화하는 동작
- **백본 영역·영역 경계 라우터(Area Border Router, ABR)**: 영역 0과 다른 영역을 연결하는 중심 영역과 영역별 경로 정보를 중계·요약하는 라우터
- **경로 요약(Route Summarization)**: 여러 연속 프리픽스를 하나의 공통 상위 프리픽스로 광고하는 기법
- **다중 접속 링크(Multi-Access Link)**: 여러 라우터가 같은 이더넷 같은 하나의 공유 링크에 연결된 환경
- **지정 라우터·백업 지정 라우터(Designated Router/Backup Designated Router, DR/BDR)**: '디알 슬래시 비디알'로 읽고 대표와 예비 역할의 머리글자를 슬래시로 나눠 공유 링크의 LSA 교환 관계를 줄이는 라우터를 구분
- **최대 전송 단위(Maximum Transmission Unit, MTU)**: 한 링크가 분할 없이 전달할 수 있는 최대 패킷 크기
- **링크 로컬 주소(Link-Local Address)**: IPv6에서 같은 링크의 이웃과만 통신하도록 자동 구성하는 주소
- **라우팅 정보 프로토콜(Routing Information Protocol, RIP)**: 이웃에게 목적지별 홉 수를 전달하는 거리 벡터 내부 라우팅 프로토콜

## Ⅰ. 개요

- 정의/개념: LSA 동기화 후 **SPF로 경로를 계산하는 IGP**
- **배경/필요성**: 거리 벡터의 **느린 수렴·루프 한계** 해소

### 쉽게 이해하기 (학습용)
- 같은 구역의 라우터들이 동일한 도로 지도를 맞춘 뒤 각자 자신에서 출발하는 가장 싼 길을 계산한다

## Ⅱ. 특징

- 영역 내 LSDB의 **토폴로지 정보 동기화**
- LSA 플러딩의 **링크 변화 신속 전파**
- 영역 분할의 **LSA·SPF 계산 범위 제한**

### 쉽게 이해하기 (학습용)

- 한 도로가 바뀌면 그 구역에만 새 지도 조각을 퍼뜨려 모든 라우터가 같은 지도에서 길을 다시 계산한다

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    subgraph B["백본 영역"]
        D0["백본 영역 LSDB"]
    end
    A["영역 경계 라우터"]
    subgraph N["비백본 영역"]
        IR["내부 라우터"]
        D1["비백본 영역 LSDB"]
        IR --- D1
    end
    A --- D0
    A --- IR
```

| 설계 요소 | 설명 |
|:---|:---|
| 백본 영역 | 다른 모든 영역의 경로 교환 중심 |
| 백본 영역 LSDB | 영역 0의 LSA와 토폴로지를 보관 |
| 영역 경계 라우터 | 영역 간 경로를 중계·요약 |
| 비백본 영역 | LSA 전파·SPF 계산 범위를 분리 |
| 내부 라우터 | 한 영역의 LSDB로 경로를 계산 |
| 비백본 영역 LSDB | 해당 영역의 LSA와 토폴로지를 보관 |

> 요약: ABR이 영역 LSDB 경계와 경로 교환을 연결

### 쉽게 이해하기 (학습용)

- 각 구역은 자기 지도를 따로 관리하고 경계 라우터가 중심 구역을 통해 다른 구역의 길을 알려 준다

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant A as 라우터 A
    participant B as 라우터 B
    participant D as LSDB
    participant R as 라우팅 테이블
    A->>B: 헬로 교환
    A->>B: 데이터베이스 요약 교환
    A->>B: LSA 요청
    B-->>A: LSA 플러딩
    A->>D: LSDB 동기화
    A->>A: SPF 계산
    A->>R: 경로 설치
```

| 절차 | 설명 |
|:---|:---|
| 헬로 교환 | 영역·인증·타이머 조건으로 이웃 확인 |
| 데이터베이스 요약 교환 | 보유 LSA 목록과 판본을 비교 |
| LSA 요청 | 없거나 오래된 LSA를 이웃에 요청 |
| LSA 플러딩 | 최신 LSA를 영역 이웃에게 전달 |
| LSDB 동기화 | 수신 LSA를 검증해 공통 지도 갱신 |
| SPF 계산 | 링크 비용으로 최단 경로 트리 계산 |
| 경로 설치 | 최선 경로를 라우팅 테이블에 반영 |

> 요약: LSDB 판본 일치 후 SPF 경로를 설치

### 쉽게 이해하기 (학습용)

- 이웃끼리 가진 지도 목록을 비교해 빠진 조각을 받은 뒤 최단 경로를 다시 계산해 안내표에 올린다

## Ⅴ. 종류 및 비교

| OSPF 버전 | OSPFv2 | OSPFv3 |
|:---|:---|:---|
| 적용 기준 | IPv4 내부 라우팅 | IPv6 기본·확장 시 IPv4 지원 |
| 핵심 특징 | IPv4 프리픽스와 LSA 결합 | 프리픽스와 링크 정보 분리 |
| 한계 | 영역·인증 불일치 | 링크 로컬·영역 설정 불일치 |

> 요약: OSPFv3는 주소와 토폴로지 광고를 분리

### 쉽게 이해하기 (학습용)

- 기존 OSPF는 IPv4 주소를 지도와 함께 다루고 OSPFv3는 링크 지도와 IPv6 주소 정보를 나눠 다룬다

## Ⅵ. 실무 사례

1. 대규모 망을 **영역 0·ABR·경로 요약으로 분할**
2. 공유 링크는 **DR·BDR로 인접 관계 축소**
3. OSPF 인접 장애는 MTU·헬로 타이머 일치 확인

### 쉽게 이해하기 (학습용)

- 큰 내부망을 구역으로 나누고 경계에서 경로를 묶으면 한 구역 변화가 전체 계산을 흔드는 범위를 줄인다
- 여러 라우터가 한 링크를 공유하면 대표와 예비를 정해 서로 맺을 관계 수를 줄인다
- 이웃 관계가 맺어지지 않으면 패킷 크기와 인사 주기 설정이 서로 같은지 확인한다

## Ⅶ. 결론

- **변화 범위·주소 체계**로 영역·OSPF 버전 결정

### 쉽게 이해하기 (학습용)
- 변화가 퍼질 범위와 쓸 주소 체계를 먼저 정해야 구역 크기와 OSPF 버전을 맞출 수 있다
