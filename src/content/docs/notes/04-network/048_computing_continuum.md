## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨팅 연속체(Computing Continuum)**: 스마트폰(말단)부터 동네 기지국(에지), 서울 본사(클라우드)까지 흩어져 있는 수만 대의 컴퓨터 자원을 마치 '하나의 거대한 컴퓨터'처럼 묶어서 돌리는 마법의 분산 패러다임이다.
- **SLO(서비스 수준 목표)**: "핑은 무조건 10ms 이하, 트래픽은 1Gbps 이상 뽑아라" 하고 시스템이 절대적으로 지켜야 하는 성능 커트라인(목표치)이다.

</details>

- 정의: 폰, 에지 서버, 중앙 클라우드에 흩어진 파편화된 컴퓨팅 자원을 **하나의 가상화 환경(단일 제어면)으로 묶고**, 요구 성능(SLO)에 맞춰 앱(워크로드)을 가장 쾌적한 자리로 알아서 이사(마이그레이션)시켜 주는 아키텍처다.
- 배경: 엣지는 엣지대로, 클라우드는 클라우드대로 따로 놀아서(Silo) 자원이 남아도는데도 통신망이 터지는 뻘짓을 막고, **스마트폰이 차를 타고 이동해도 앱 서비스가 끊김 없이 찰거머리처럼 따라오게 하려고 만들었다.**

#### 한줄 요약

- 단말부터 우주(클라우드)까지 세상 모든 컴퓨터를 하나로 묶고, 앱을 제일 쾌적한 빈자리로 휙휙 던져(이사)주는 극한의 효율 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워크로드 이식성(Workload Portability)**: 윈도우, 리눅스, 폰, 클라우드 환경 안 가리고 짐(컨테이너)을 싸서 던지면 0.1초 만에 바로 그 자리에서 똑같이 앱이 켜지는 유연함이다.
- **데이터 중력(Data Gravity)**: 100TB짜리 영상 데이터를 서울 클라우드로 보내려다 통신비가 수억 깨지니까, 차라리 가벼운 분석 앱을 데이터가 모여있는 부산(에지)으로 끌어내리는(중력) 현상이다.

</details>

- **하나로 퉁쳐서 관리 (단일 추상화)**: K8s(쿠버네티스) 기술로 전 세계에 흩어진 수만 대의 서버 CPU를 묶어서 내 모니터 한 화면에 하나의 컴퓨터처럼 띄워버림.
- **데이터 중력 기반 눈치 게임**: 무식하게 무거운 데이터를 클라우드로 낑낑 옮기지 않고, 데이터가 모여 있는 쪽에 앱을 깔아서 연산하는 '가성비 오케스트레이션'을 때림.
- **유연한 짐 싸기 (동적 재배치)**: 강남역 에지 서버가 터질 것 같으면, 알아서 여유로운 판교 클라우드나 역삼역 에지로 앱(컨테이너)을 실시간 이사시켜 버림.

#### 한줄 요약

- 전국 CPU를 하나로 통일하고, 무거운 데이터 냅두고 가벼운 앱을 이동시키며, 서버 터지기 전에 알아서 쾌적한 곳으로 짐 싸서 튄다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **통합 제어면(Unified Control Plane)**: 전국의 폰, 에지, 클라우드 CPU 상태를 실시간으로 훔쳐보고 "너는 여기로 가, 너는 저기로 가" 하고 교통정리를 해주는 전국구 총사령관이다.

</details>

```text
[ 컴퓨팅 연속체 팩트 폭행 구조 ]

[ 통합 제어면 (전국구 총사령관, K8s Federation) ] ── (실시간 자원 감시 및 앱 이사 명령)
      │
      ▼ (어디로 보낼지 결정)
[ 중앙 클라우드 ] ──▶ (본사 회장님: 대규모 딥러닝, 장기 백업)
      │
[ 근접 에지 (Near) ] ──▶ (동네 반장: 지역 트래픽 묶음, 영상 캐시)
      │
[ 최말단 에지 (Far) ] ──▶ (현장 반장: 기계 바로 옆에서 1ms 즉각 제어)
      │
[ IoT 스마트 단말 ] ──▶ (노가다 기계: 데이터 무한 생성)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **통합 제어면 (Control Plane)** | 폰부터 클라우드까지 싹 다 감시하면서 **앱들 이사(마이그레이션)시키는 총사령관** | K8s Federation |
| **중앙 클라우드** | 데이터 중력이 제일 커서 **무거운 딥러닝 돌리고 백업하는 본사 회장님** | Central Cloud |
| **근접 에지 (Near)** | 기지국 근처에 살면서 **동네 트래픽 1차로 걸러내는 지역 짬처리 반장** | Regional Edge |
| **최말단 에지 (Far)** | 공장 기계 바로 옆에 붙어서 **0.001초 만에 브레이크 밟는 즉결 행동대장** | Far Edge |
| **글로벌 상태 연동망** | 앱이 부산에서 서울로 이사 갈 때 **데이터 안 날아가게 고속 복붙해 주는 망** | State Sync |

#### 한줄 요약

- 총사령관(제어면) 밑에 회장님(클라우드), 동네 반장(근접), 행동대장(말단)이 쫙 깔려서 자원을 영혼까지 끌어다 쓰는 융합 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ 짐 싸서 이사 가는 (재배치) 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [전국구 자원 팩트 체크]   │
│ (사령관: 강남 에지 CPU 100% 찼네?)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [데이터 위치(중력) 스캔]  │
│ (데이터가 다 판교에 몰려있음)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [최적 이사 견적(SLO) 뽑기]│
│ (핑 10ms 맞추려면 역삼 에지로 보내자)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [컨테이너 앱 고속 이사 (복붙)]
│ (강남 $\to$ 역삼으로 앱 0.1초 만에 이관)
└──────────────────────────────┘
```

### 동작 원리

1. 전국 텔레메트리 모니터링: 총사령관이 전 세계 서버의 CPU, 램, 통신 핑 상태를 실시간으로 훔쳐봄.
2. 데이터 위치 팩트 체크: 이사 갈 앱의 무거운 데이터(중력)가 지금 어디에 저장되어 있는지 확인함.
3. SLO 기반 최적 스케줄링: 핑(지연시간) 제한 조건을 어기지 않으면서 가장 여유로운 서버를 꿀자리로 지정함.
4. 컨테이너 워크로드 마이그레이션: 기존 서버에서 앱을 통째로 얼려서(Snap) 새 서버로 0.1초 만에 던져서 다시 깨움(복붙).

#### 한줄 요약

- 전국 CPU 감시하다가 터질 거 같으면, 데이터 위치랑 핑(SLO) 계산해서 제일 쾌적한 꿀자리로 앱을 짐 싸서 던져버림.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고립 운영(Siloed Operation)**: 클라우드는 클라우드팀이, 에지는 에지팀이 알아서 굴려서 서로 CPU가 남아도 안 빌려주는 이기적인 꼰대 방식이다.

</details>

| 비교 항목 | **컴퓨팅 연속체 (Continuum)** | **기존 고립 운영 (Siloed Edge/Cloud)** |
|:---|:---|:---|
| 팩트 폭행 비유 | 전국 지점이 자원 셰어하는 **하나의 대기업** | 지들끼리 밥그릇 챙기는 **독립 가맹점들** |
| 제어 및 관리 | 전국의 모든 컴퓨터를 **한 화면에서 완벽히 통제함** | 클라우드 따로, 에지 따로 **파편화 됨** |
| 앱(워크로드) 배치 | 데이터 위치와 핑(SLO) 쳐다보고 **AI가 알아서 꿀자리에 박아줌** | 개발자가 처음 세팅한 **그 자리에 죽을 때까지 박혀있음** |
| 자원 효율성 | 에지가 뻗으면 클라우드 CPU **마음대로 빌려 써서 효율 극강** | 딴 데 자원이 텅텅 비어도 **절대 안 빌려줘서 터짐** |
| 단점 (리스크) | 전국 동기화하고 감시하느라 **시스템 구축이 토 나옴** | 그냥 각자 굴리면 돼서 초기 구축은 맘 편함 |

#### 한줄 요약

- 각자도생 하던 에지와 클라우드를 하나로 멱살 잡고 묶어서, 자원 낭비를 0%로 수렴시키는 게 컴퓨팅 연속체다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SPIFFE(워크로드 신원)**: 앱이 강남에서 역삼으로 이사 갈 때, "나 해커 아니고 아까 그 앱 맞음" 하고 암호화된 주민등록증(신원)을 까서 인증하는 체계다.
- **중복 실행(Dual Active Conflict)**: 앱이 이사 가는 도중에, 강남(구) 서버랑 역삼(신) 서버가 둘 다 켜져서 똑같은 데이터를 두 번 결제해 버리는 대참사다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 데이터 옮기느라 **통신비가 수백억이 깨짐** | CPU 비어있다고 데이터(중력) 무시하고 **앱을 엉뚱한 데로 보내서 핑이 터짐** | **데이터 중력(Data Gravity)** 계산해서 수송비 아끼는 곳으로 이사시킴 | 망 대역폭 파탄 나는 거 컷 및 쾌적함 유지 |
| 앱이 이사 갔는데 **권한 없다고 접속 차단당함** | 에지랑 클라우드 간 보안 정책(방화벽)이 완전히 다름 | **SPIFFE** 기반 암호화 주민등록증 까서 **통합 신원 인증 빡세게 돌림** | 미승인 깡통 앱 컷 및 찰떡같은 보안 유지 |
| 이사 도중에 양쪽 다 켜져서 **데이터 두 번 결제(덮어쓰기)됨** | 이전 노드랑 신규 노드 앱이 **동시에 켜지는(Dual Active) 충돌 대참사** | **Make-before-break (락 걸고 넘기기)** 적용해서 트랜잭션 꼬임 방지 | 덮어쓰기 대참사 방어 및 무결성 떡상 |
| 에지 서버가 뻗었는데 **총사령관이 파악을 못 함** | 하드웨어 종류가 너무 많아서 CPU 상태 측정이 안 됨 | **eBPF(커널 직결 감시)** 기술로 전 세계 노드 샅샅이 스캔함 | 실시간 CPU/메모리 감시 및 꿀자리 배치 |

#### 한줄 요약

- 통신비 안 깨지게 데이터 중력 계산하고, 이사 갈 땐 신원 인증(SPIFFE) 빡세게 하며, 양쪽 다 켜져서 데이터 덮어쓰는 뻘짓을 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **재배치 이득(Relocation Net Gain)**: 앱을 이사시켜서 얻는 속도 이득보다 이사(데이터 복붙) 통신 비용이 더 비싸면 차라리 이사를 안 가는 게 낫다는 손익 계산법이다.

</details>

- 엣지와 클라우드의 고립된 사일로(Silo)를 타파하기 위해, 단일 **제어면(Unified Control Plane)** 으로 묶어 **데이터 중력**과 SLO 기반 워크로드 마이그레이션을 밥 먹듯이 수행하는 컴퓨팅 연속체 기조 확립함

#### 한줄 요약

- 컴퓨팅 연속체는 "내 컴퓨터, 네 컴퓨터" 가리지 않고 지구 전체를 '거대한 컴퓨터 한 대'로 갈아 엎는 클라우드의 최종 진화 형태다.
