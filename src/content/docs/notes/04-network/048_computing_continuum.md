## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨팅 연속체(Computing Continuum / Cloud-Edge Continuum)**: 초말단 IoT 단말(Far Edge), 기지국/현장 엣지(Near Edge), 지역 데이터센터(Regional Edge), 중앙 클라우드(Central Cloud)에 분산된 이기종 컴퓨팅 자원을 단일 논리적 가상화 제어면(Unified Control Plane)으로 통합하여 워크로드를 동적 오케스트레이션하는 분산 컴퓨팅 아키텍처.
- **서비스 수준 목표(Service Level Objective, SLO)**: 특정 워크로드가 요구하는 최대 허용 지연 시간(Latency), 처리 대역폭, 가용성 지표의 정량적 목표 기준.

</details>

- 정의/개념: IoT 단말부터 중앙 클라우드까지의 파편화된 자원을 **단일 추상화 계층** 으로 결합하고, **데이터 중력(Data Gravity)** 과 **SLO** 요구조건에 따라 컨테이너 워크로드를 최적 위치로 자율 스케줄링·마이그레이션하는 **차세대 분산 컴퓨팅 패러다임**
- 배경/필요성: 엣지와 클라우드가 개별 사일로(Silo)로 분리 운영되어 발생하는 자원 비효율을 제거하고, 단말의 지리적 이동 시에도 끊김 없는 상태 보존형(Stateful) 저지연 서비스를 실현할 요구

#### 한줄 요약
- IoT부터 클라우드까지 전 계층 자원을 통합하여 SLO와 데이터 중력 기반으로 워크로드를 자율 배치한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워크로드 이식성(Workload Portability)**: OCI(Open Container Initiative) 표준 컨테이너 및 WebAssembly(WASM) 기반으로 이기종 CPU 아키텍처(x86, ARM, RISC-V) 간에 수정 없이 워크로드를 즉시 재배치할 수 있는 능력.
- **데이터 중력(Data Gravity)**: 대용량 데이터 세트가 축적될수록 네트워크 전송 비용과 지연으로 인해 연산 애플리케이션이 데이터가 위치한 물리적 장소로 끌어당겨져 실행되는 원리.

</details>

- **단일 통합 제어면(Unified Control Plane)**: K8s Federation, KubeEdge 등을 통해 분산 클러스터 전체의 가용 자원과 네트워크 토폴로지를 단일 뷰로 추상화
- **데이터 중력 기반 비용 최적화**: 대용량 원시 데이터의 WAN 전송 비용을 방지하기 위해 연산 로직을 데이터 생성지 인접 노드로 전진 배치
- **동적 상태 보존형 마이그레이션(Live Migration)**: 단말 이동 및 노드 부하 변동 시 워크로드 상태(State)를 보존하며 무중단으로 인접 엣지/클라우드로 재배치

#### 한줄 요약
- 단일 통합 제어면, 데이터 중력 기반 배치, 무중단 상태 보존 워크로드 마이그레이션을 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **통합 제어면(Unified Control Plane)**: 전 계층 노드의 텔레메트리(CPU, GPU, RAM, 네트워크 RTT)를 실시간 수집하고 최적의 스케줄링 정책을 집행하는 상위 오케스트레이션 엔진.

</details>

```text
[ 통합 제어면 (Unified Orchestrator / Multi-Cluster Manager) ]
   │ (전 계층 자원 텔레메트리 수집 및 SLO 기반 스케줄링)
   ├───────────────────────────────┬───────────────────────────────┐
   ▼                               ▼                               ▼
[ 중앙 클라우드 ]             [ 근접 엣지 (Near Edge) ]      [ 초말단 엣지 (Far Edge / IoT) ]
 ├─ 전역 빅데이터 웨어하우스    ├─ MEC 국사 / 지역 데이터센터   ├─ 현장 PLC / 스마트 센서
 ├─ 대규모 AI 모델 학습         ├─ 데이터 캐시 및 요약 집계     ├─ 1ms 즉시 액추에이터 제어
 └─ 장기 배치 프로세싱          └─ 마이크로서비스 동적 호스팅   └─ 원시 데이터 실시간 수집
```

선의 의미: 상위 오케스트레이터가 전 계층 노드를 통합 관리하며, 워크로드는 연산 강도와 지연 요구에 따라 적절한 계층 노드로 상하 배치되는 구조

| 계층 | 대표 인프라 | 책임 및 역할 | 전형적 RTT |
|:---|:---|:---|:---|
| **중앙 클라우드 (Central)** | AWS, Azure, 전용 IDC 서버 팜 | 전역 데이터 집중 분석, 대규모 AI 훈련, 영구 스토리지 | 50 ~ 100 ms |
| **근접 엣지 (Near Edge)** | 통신사 국사 MEC, 지역 PoP | 트래픽 오프로딩, 미디어 스트리밍 캐시, 중간 집계 | 10 ~ 20 ms |
| **초말단 엣지 (Far Edge)**| 산업용 게이트웨이, 스마트 기기 | 현장 데이터 필터링, 1ms 초저지연 결정론적 제어 | 1 ~ 5 ms |
| **상태 동기화 버스** | 분산 etcd, 메시징 큐, gRPC | 노드 간 세션 데이터 및 컨테이너 체크포인트 고속 복제 | 지연 동기화 |

#### 한줄 요약
- 통합 오케스트레이터, 중앙 클라우드, 근접 엣지, 초말단 엣지가 계층적으로 결합하여 연속체를 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스케줄링 알고리즘**: 가용 CPU/메모리, 노드 간 네트워크 RTT, 데이터 상주 위치, 전송 비용을 다차원 목적 함수로 계산하여 최적 호스트를 결정하는 알고리즘.

</details>

```text
1. 통합 제어면이 eBPF 및 텔레메트리 에이전트를 통해 전 계층 노드의 자원/네트워크 지연 모니터링
            │
            ▼
2. 서비스 요청 수신 시 워크로드의 SLO(최대 허용 지연, 연산량) 및 데이터 저장 위치(데이터 중력) 분석
            │
            ▼
3. 다차원 최적화 스케줄러가 비용-지연 트레이드오프를 평가하여 최적 배치 계층(Far/Near/Cloud) 선정
            │
            ▼
4. 컨테이너 이미지 및 상태 스냅샷을 대상 노드로 전송 ➔ Make-before-break 방식으로 무중단 기동
```

**동작 원리**

1. **글로벌 텔레메트리 계측**: 전 계층의 CPU 부하율과 링크 RTT를 실시간 프로빙하여 토폴로지 맵 갱신
2. **데이터 중력 판정**: 처리할 데이터 용량이 클 경우 데이터를 이동시키지 않고 연산 컨테이너를 데이터 로컬 노드로 스케줄링
3. **SLO 기반 배치**: 1ms 저지연 요구 시 Far Edge로, 대규모 병렬 연산 요구 시 Central Cloud로 태스크 분기
4. **무중단 마이그레이션**: 신규 노드에서 인스턴스를 사전 기동하고 세션을 전환한 후 구 인스턴스를 정리(Make-before-break)하여 서비스 단절 방지

#### 한줄 요약
- 텔레메트리 감시, SLO/데이터 중력 분석, 최적 계층 스케줄링, Make-before-break 무중단 기동 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사일로화된 고립 운영(Siloed Operation)**: 클라우드와 엣지가 독립된 관리 도구와 서로 다른 인터페이스로 격리되어 자원 공유 및 동적 이동이 불가능한 기존 운영 방식.

</details>

| 비교 항목 | 컴퓨팅 연속체 (Computing Continuum) | 전통적 사일로 운영 (Siloed Edge/Cloud) |
|:---|:---|:---|
| **자원 통합성** | **전 계층 단일 논리 가상 자원 풀로 통합** | 엣지와 클라우드가 개별 사일로로 파편화 |
| **제어 및 관리** | **K8s Federation 기반 통합 단일 제어면** | 인프라 계층별 상이한 관리 콘솔 수동 운영 |
| **워크로드 배치** | **SLO 및 데이터 중력에 따른 동적 자동 재배치** | 개발자가 특정 서버 IP에 정적 고정 배포 |
| **자원 활용률** | 국소 부하 발생 시 타 계층으로 오프로딩하여 극대화 | 특정 노드 과부하 시에도 타 노드 유휴 자원 활용 불가 |
| **구축 복잡도** | 분산 오케스트레이션 및 상태 동기화 메커니즘 요구 | 독립 인프라 단위 구축으로 상대적 단순 |

#### 한줄 요약
- 컴퓨팅 연속체는 전 계층 자원을 통합하여 동적 자동 배치를 실현하며, 기존 사일로의 자원 파편화를 극복한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SPIFFE / SPIRE**: 분산되고 동적으로 마이그레이션되는 이기종 환경의 워크로드에 암호학적으로 검증 가능한 고유 신원 문서(SVID, X.509/JWT)를 자동 발급하는 표준 프레임워크.
- **스플릿 브레인(Split-Brain / Dual Active)**: 마이그레이션 도중 네트워크 분할로 인해 구 노드와 신 노드가 동시에 활성화되어 데이터 정합성이 파괴되는 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 데이터의 무분별한 WAN 전송으로 인한 네트워크 비용 폭증 및 병목 | **데이터 중력(Data Gravity)** 인지형 스케줄링 및 엣지 로컬 연산 강제 | 백홀 데이터 전송량 80% 이상 절감 및 비용 최적화 |
| 이종 인프라(클라우드 $\leftrightarrow$ 엣지) 간 워크로드 이동 시 인증 및 접근 권한 단절 | **SPIFFE/SPIRE 기반 암호화 워크로드 신원(SVID)** 통합 관리 | 인프라 위치 무관 제로 트러스트 상호 인증 보장 |
| 실시간 워크로드 마이그레이션 중 분산 노드 간 동시 쓰기(Dual Active) 충돌 | 분산 분산 락(Distributed Lock) 및 **Make-before-break 세션 인계** 적용 | 데이터 덮어쓰기 방지 및 트랜잭션 무결성 보증 |

#### 한줄 요약
- 데이터 중력 스케줄링으로 통신 비용을 절감하고, SPIFFE로 통합 신원을 보장하며, Make-before-break로 정합성을 유지한다.

## Ⅶ. 결론

- 클라우드와 엣지의 경계를 허물고 초저지연과 대규모 연산 효율을 동시에 달성하기 위해 **컴퓨팅 연속체(Computing Continuum)** 아키텍처를 도입하되, 이기종 분산 인프라의 운영 안정성을 보장하기 위해 **K8s 기반 단일 오케스트레이션 제어면**, **데이터 중력 최적화 알고리즘**, **SPIFFE 제로 트러스트 신원 체계**를 통합 구축하여 지능형 분산 컴퓨팅 환경을 완성

#### 한줄 요약
- 단일 제어면, 데이터 중력 최적화, SPIFFE 신원 체계를 결합하여 고효율 컴퓨팅 연속체를 실현한다.
