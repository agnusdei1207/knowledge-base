## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Computing Continuum (컴퓨팅 연속체)**: IoT 단말(Far Edge), 기지국(Near Edge), 중앙 클라우드에 분산된 이기종 자원을 단일 제어면으로 묶어 오케스트레이션하는 아키텍처.
- **Data Gravity (데이터 중력)**: 데이터의 크기가 클수록 데이터를 이동시키는 대신 연산 애플리케이션을 데이터 발생지 인근으로 끌어당겨 배치하는 원리.

</details>

- 정의/개념: IoT 단말부터 중앙 클라우드까지의 파편화된 자원을 **단일 가상화 제어면으로 통합하고 데이터 중력과 SLO에 따라 워크로드를 동적 배치하는 분산 인프라 아키텍처**
- 배경/필요성: 클라우드와 엣지가 분리된 기존 사일로 운영의 한계로 인한 **대용량 데이터 WAN 전송 비용 폭증, 노드 간 워크로드 동적 마이그레이션 및 단일 제어 불가**

#### 한줄 요약
- 단일 제어면을 통해 IoT부터 클라우드까지의 자원을 묶고, 데이터 중력에 따라 워크로드를 동적 배치한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Unified Control Plane (통합 제어면)**: Kubernetes Federation 또는 KubeEdge/K3s 기반으로 전 계층 노드의 텔레메트리를 수집하고 파드를 스케줄링하는 단일 관제점.
- **Live Migration (상태 보존 마이그레이션)**: 단말 이동 시 세션 상태(State)를 손실 없이 복제하여 인접 엣지 호스트로 무중단 인계(Make-before-break)하는 기술.

</details>

- **단일 논리 가상 자원 풀 형성**: K8s Federation 기반으로 이종 인프라를 단일 추상화 계층으로 통합
- **데이터 중력 기반 비용 최적화**: 대용량 원시 데이터의 WAN 전송을 막기 위해 연산 로직을 데이터 생성지로 전진 배치
- **동적 상태 보존형 마이그레이션**: 단말 이동 및 부하 변동 시 워크로드 상태를 보존하며 무중단으로 엣지/클라우드 간 재배치

#### 한줄 요약
- 단일 통합 제어면, 데이터 중력 기반 배치, 무중단 상태 보존 워크로드 마이그레이션을 지원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Far Edge vs Near Edge vs Central Cloud**: 1~5ms 초말단 기기(Far Edge), 10~20ms 통신사 국사 MEC(Near Edge), 50~100ms 중앙 데이터센터(Central Cloud).

</details>

```text
[컴퓨팅 연속체 계층 및 단일 제어면 오케스트레이션 아키텍처]
|-- Unified Control Plane (K8s Multi-Cluster Manager / E2E Orchestrator)
|   `-- Resource Telemetry & SLO Scheduler (CPU, GPU, RAM, RTT, 데이터 중력 분석)
|-- Central Cloud Layer (AWS, Azure, IDC 서버 팜: 대규모 AI 모델 학습, 빅데이터 분석, >50ms)
|-- Near Edge Layer (통신사 국사 MEC, 지역 PoP: 데이터 캐싱, 마이크로서비스 호스팅, 10~20ms)
`-- Far Edge / IoT Layer (현장 게이트웨이, 스마트 센서, PLC: 1ms 즉각 제어, 원시 데이터 수집, 1~5ms)
`-- State Synchronization Bus (분산 etcd, gRPC, 메시징 큐 기반 상태 실시간 복제)
```

선의 의미: 계층 및 상위 오케스트레이터가 전 계층 노드를 통합 관리하며 워크로드는 연산 강도와 지연 요구에 따라 적절한 계층 노드로 상하 배치되는 구조

| 계층 | 대표 인프라 | 핵심 엔지니어링 책임 | 전형적 RTT |
|:---|:---|:---|:---|
| **중앙 클라우드 (Central)** | AWS, Azure, 전용 IDC 서버 팜 | **전역 데이터 집중 분석, 대규모 AI 훈련, 영구 스토리지** | **50 ~ 100 ms** |
| **근접 엣지 (Near Edge)** | 통신사 국사 MEC, 지역 PoP | **트래픽 오프로딩, 미디어 스트리밍 캐시, 중간 집계** | **10 ~ 20 ms** |
| **초말단 엣지 (Far Edge)** | 산업용 게이트웨이, 스마트 기기| **현장 데이터 필터링, 1ms 초저지연 결정론적 제어** | **1 ~ 5 ms** |
| **상태 동기화 버스** | 분산 etcd, gRPC, 메시징 큐 | **노드 간 세션 데이터 및 컨테이너 체크포인트 고속 복제** | 지연 동기화 |

#### 한줄 요약
- 통합 오케스트레이터, 중앙 클라우드, 근접 엣지, 초말단 엣지가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Make-before-break**: 이전 노드의 세션을 끊기 전에 타깃 노드에서 신규 컨테이너와 상태를 먼저 정상 가동시킨 후 트래픽을 인계하는 무중단 기법.

</details>

```text
컴퓨팅 연속체 워크로드 동적 스케줄링 파이프라인
        │
   1. [글로벌 텔레메트리 계측] 전 계층 노드의 CPU/RAM 부하율 및 네트워크 RTT 실시간 수집
        │
   2. [SLO 및 데이터 중력 판정] 워크로드의 지연 한도(1ms vs 100ms)와 데이터 용량 평가
        │
   3. [최적 배치 계층 선정] 다차원 최적화 스케줄러가 Far Edge / Near Edge / Cloud 중 최적 노드 결정
        │
   ▼
4. [Make-before-break 무중단 기동] 타깃 노드 사전 기동 및 상태 동기화 후 트래픽 무중단 절체
```

#### 한줄 요약
- 텔레메트리 감시 → SLO/데이터 중력 분석 → 최적 계층 스케줄링 → Make-before-break 무중단 기동 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Computing Continuum** vs **Siloed Operation**: 전 계층 통합 단일 제어면(연속체)과 인프라별 분리 고립 운영(사일로).

</details>

| 비교 항목 | 컴퓨팅 연속체 (Computing Continuum) | 전통적 사일로 운영 (Siloed Edge/Cloud) |
|:---|:---|:---|
| **자원 통합성** | **전 계층 단일 논리 가상 자원 풀로 통합** | 엣지와 클라우드가 개별 사일로로 파편화 |
| **제어 및 관리** | **K8s Federation 기반 통합 단일 제어면** | 인프라 계층별 상이한 콘솔 수동 개별 운영 |
| **워크로드 배치** | **SLO 및 데이터 중력에 따른 동적 자동 재배치** | 개발자가 특정 서버 IP에 정적 고정 배포 |
| **자원 활용 효율**| 국소 부하 시 타 계층으로 오프로딩 극대화 | 특정 노드 과부하 시에도 타 노드 유휴 자원 활용 불가 |
| **구축 복잡도** | 분산 오케스트레이션 및 상태 동기화 요구 | 독립 인프라 단위 구축으로 상대적 단순 |

#### 한줄 요약
- 컴퓨팅 연속체는 전 계층 자원을 통합하여 동적 자동 배치를 실현하며, 기존 사일로의 자원 파편화를 극복한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SPIFFE / SPIRE**: 분산되고 동적으로 마이그레이션되는 이기종 워크로드에 암호학적 X.509 신원(SVID)을 자동 발급하는 표준 프레임워크.
- **Dual Active (동시 쓰기 충돌)**: 마이그레이션 도중 네트워크 단선으로 인해 구 노드와 신 노드가 동시에 쓰기 작업을 수행하여 정합성이 깨지는 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 데이터의 무분별한 WAN 전송으로 인한 네트워크 비용 폭증 | **`데이터 중력(Data Gravity) 인지형 스케줄링` 및 엣지 로컬 연산** | 백홀 데이터 전송량 80% 이상 절감 및 비용 최적화 |
| 이종 인프라 간 워크로드 이동 시 인증 및 접근 권한 단절 | **`SPIFFE/SPIRE 기반 암호화 워크로드 신원(SVID)` 통합 관리** | 인프라 위치 무관 제로 트러스트 상호 인증 보장 |
| 실시간 워크로드 마이그레이션 중 분산 노드 간 동시 쓰기(Dual Active) 충돌 | 분산 분산 락(Distributed Lock) 및 **`Make-before-break 세션 인계`** | 데이터 덮어쓰기 방지 및 트랜잭션 무결성 보증 |
| Far Edge 임베디드 장비의 K8s 무거운 풋프린트 오버헤드 | **경량화 쿠버네티스 배포판(`K3s / KubeEdge`) 적용** | 512MB RAM 환경에서도 엣지 컨테이너 안정 구동 |

#### 한줄 요약
- 데이터 중력 스케줄링, SPIFFE 통합 신원, Make-before-break 정합성 보장, K3s 경량화로 운영한다.

## Ⅶ. 결론

- 클라우드와 엣지의 경계를 허물고 초저지연과 대규모 연산 효율을 동시에 달성하기 위해 **컴퓨팅 연속체(Computing Continuum) 아키텍처를 도입**하고, 이기종 분산 인프라의 운영 안정성을 보장하기 위해 **K8s 기반 단일 오케스트레이션 제어면, 데이터 중력 최적화 알고리즘, SPIFFE 제로 트러스트 신원 체계**를 통합 구축하여 지능형 분산 인프라 완성

#### 한줄 요약
- 컴퓨팅 연속체는 단일 제어면과 데이터 중력 기반 스케줄링을 통해 IoT부터 클라우드까지 전 계층 자원을 유기적으로 통합하는 차세대 분산 컴퓨팅 기술이다.
