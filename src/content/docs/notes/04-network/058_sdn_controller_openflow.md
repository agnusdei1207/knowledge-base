## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SDN 컨트롤러 (SDN Controller)**: 네트워크 망의 모든 걸 지켜보고 길을 짜주는 빅브라더 중앙 관제 두뇌(소프트웨어)다.
- **OpenFlow (오픈플로우)**: 대장(컨트롤러)이 멍청해진 깡통 스위치들한테 "이 패킷은 일로 던져!"라고 명령을 내릴 때 쓰는 사우스바운드(SBI) 표준 언어 규격이다.

</details>

- 정의: **SDN 컨트롤러와 OpenFlow**는 소프트웨어 정의 네트워킹(SDN)을 굴리는 핵심 듀오로, 전역 경로를 연산하는 관제 두뇌(**SDN Controller**)와 이를 스위치 룰북에 쑤셔 넣는 통신 규격(**OpenFlow**)을 말한다.
- 배경: 옛날엔 시스코, 주니퍼 등 벤더사마다 스위치 세팅 명령어가 다 달라서 관리자가 미쳐갔는데, **어떤 회사 스위치를 사 오든 다 똑같은 말로 조종할 수 있게 범용 표준 언어(OpenFlow)를 만들었다.**

#### 한줄 요약

- 대장(SDN 컨트롤러)이 길을 다 찾은 다음, 시다바리 스위치들한테 무전 칠 때 쓰는 표준 무전 암호(OpenFlow)다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Match-Action (매칭-액션)**: "출발지 IP 1.1.1.1(Match) $\to$ 쓰레기통에 버려라(Action)"처럼 스위치가 뇌를 비우고 기계적으로 일하게 만드는 조건반사 룰이다.
- **Table-Miss (테이블 미스)**: 스위치가 룰북에 없는 처음 보는 패킷을 받고 "대장! 이거 어떡함?" 하고 멘붕 온 상태다.

</details>

- **Match-Action 파이프라인**: 스위치는 IP, MAC 주소(Match 조건)만 보고 사전에 지시받은 대로 컷트, 전달, 변조(Action)하는 무지성 노가다만 뛴다.
- **Table-Miss 헬프 요청**: 룰북(흐름 테이블)에 없는 미지 패킷이 나타나면, 깡통 스위치는 혼자 결정 못 하고 바로 컨트롤러 대장한테 보고서(Packet-In)를 날려 헬프를 친다.
- **그룹/미터 테이블 확장**: 단순히 1:1로 전달하는 걸 넘어, 1:N으로 복사해서 뿌리거나(Group) 다운로드 속도 제한 락을 거는(Meter) 고급 액션도 수행한다.

#### 한줄 요약

- 스위치는 무지성으로 조건(Match)-실행(Action)만 하고, 룰북에 없는 놈이 오면 냅다 대장한테 보고(Table-Miss)하는 군대식 구조다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Packet-In**: 스위치가 모르는 패킷을 받았을 때 대장한테 "이거 어떡해요?" 하고 올려보내는 보고서 메시지다.
- **Flow-Mod**: 보고서를 받은 대장이 "이렇게 처리해라" 하고 스위치 머리통에 꽂아버리는 하달 명령서다.
- **흐름 테이블 (Flow Table)**: 깡통 스위치가 매일 쳐다보는 행동 강령(룰북)이다. 비싸고 빠른 TCAM 하드웨어 메모리에 저장된다.

</details>

```text
[ 컨트롤러와 OpenFlow 팩트 폭행 구조 ]

[ 제어 평면 (SDN 컨트롤러 대장) ]
      ▲ (Packet-In: 대장님 이거 어떡함?)
      │
  (보안 채널 TLS/TCP 6653)
      │
      ▼ (Flow-Mod: 이렇게 처리해라 룰 주입 쾅!)
[ 데이터 평면 (OpenFlow 깡통 스위치) ]
      │
      ▼ (흐름 테이블 룰북 보고 무지성 패킷 포워딩)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **SDN 컨트롤러** | 보고서(Packet-In) 받고 길 찾아서 **명령서(Flow-Mod) 내려보내는 빅브라더** | Control |
| **보안 채널 (TLS)** | 대장이랑 깡통 스위치가 통신할 때 **해커가 못 엿듣게 뚫어놓은 암호화 파이프** | Channel |
| **흐름 테이블 (Flow Table)**| 스위치가 멍청하게 **시킨 대로만 액션을 취하게 만드는 행동 강령 룰북** | Data |
| **그룹/미터 테이블** | 여러 명한테 뿌리거나(그룹) 속도 제한(미터) 먹이는 **고급 룰북** | Data |

#### 한줄 요약

- 보안 채널 뚫어놓고 스위치가 징징대면(Packet-In), 컨트롤러가 룰(Flow-Mod)을 주입해서 흐름 테이블 룰북을 완성하는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ OpenFlow 흐름 주입 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [패킷 수신 및 매칭 실패]  │
│ (스위치: 헐 처음 보는 IP가 들어왔다!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [Table-Miss $\to$ Packet-In 발송]
│ (스위치: 대장님 이거 어떡해요? 헬프!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [전역 경로 연산 $\to$ Flow-Mod 주입]
│ (대장: 부산 쪽으로 보내라. 룰 주입 쾅!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [TCAM에 룰 저장 (학습 완료)]│
│ (스위치: 아하! 앞으로 이 IP는 부산으로 쏨)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [지정 액션 (무지성 포워딩)] │
│ (이후 똑같은 패킷 오면 묻지 않고 바로 쏨)
└──────────────────────────────┘
```

### 동작 원리

1. 매칭 실패 (Table-Miss): 스위치가 처음 보는 패킷을 받고 흐름 테이블(룰북)을 뒤졌는데 답이 없음.
2. Packet-In 발송: 스스로 결정 못 하니까 패킷 대가리를 떼서 컨트롤러한테 보내고 지시를 바람.
3. 연산 및 Flow-Mod 배포: 컨트롤러가 전국 지도를 보고 최적의 길을 짠 뒤, Flow-Mod 명령서로 룰을 내려꽂음.
4. TCAM 저장: 스위치가 받은 룰을 초고속 메모리(TCAM)에 저장해둠.
5. 무지성 포워딩: 이후에 똑같은 놈이 오면 대장한테 안 묻고 알아서 포워딩(Action) 처리함.

#### 한줄 요약

- 모르는 놈 오면 징징대고 $\to$ 대장이 답 알려주면 외웠다가 $\to$ 담부턴 무지성으로 자동 패스하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **반응형 제어 (Reactive Setup)**: 룰북을 비워뒀다가 모르는 패킷이 오면 그때그때 대장한테 물어보면서 룰을 채워나가는 자기주도 학습이다.
- **선제형 제어 (Proactive Setup)**: 패킷이 오기도 전에 대장이 "이건 일로 가라" 하고 룰북을 미리 꽉꽉 채워놓는 주입식 교육이다.

</details>

| 비교 항목 | **반응형 제어 (Reactive / 벼락치기)** | **선제형 제어 (Proactive / 주입식)** |
|:---|:---|:---|
| 팩트 폭행 비유 | 모를 때마다 **대장한테 징징대며 묻는 놈** | 대장이 개통 전부터 **룰북 꽉꽉 채워놓은 놈** |
| 규칙 주입 시점 | 패킷 받고(Table-Miss) 헬프 쳤을 때 **동적 주입** | 개통할 때 대장이 **일괄적으로 싹 다 정적 주입** |
| 첫 패킷 핑 지연 | 대장한테 물어보고 오느라 **첫 패킷 랙 오지게 걸림** | 이미 룰이 다 있어서 **첫 패킷 0초 컷** |
| 스위치 메모리(TCAM)| 필요한 룰만 그때그때 외워서 **메모리 절약 꿀** | 세상 모든 룰을 다 외우고 있어서 **메모리 터짐** |
| 대장(컨트롤러) 부하 | 뻑하면 물어봐서 **대장 CPU 폭발함 (과부하)** | 한 번만 알려주면 끝이라 **대장 꿀 빰** |

#### 한줄 요약

- 반응형은 첫 핑이 느리지만 스위치 메모리를 아끼고, 선제형은 엄청 빠르지만 스위치 메모리가 터져나간다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Idle/Hard Timeout (유휴/강제 만료)**: 스위치의 비싼 TCAM 하드웨어 메모리가 쓰레기 룰로 꽉 차서 뻗지 않게, 일정 시간 안 쓴 룰(Idle)이나 유효기간 지난 룰(Hard)을 자동 폭파시키는 메모리 청소 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 미지 패킷(DDoS) 폭주 시 **컨트롤러 대장 CPU가 터짐** | 스위치가 핑 찍힐 때마다 모른다고 Packet-In을 수십만 개씩 날려댐 | 대장한테 징징대는 양을 조절하는 **Packet-In Rate Limiting 컷트 룰 적용** | 대장 서버 마비 방지 및 무지성 질의 차단 |
| 스위치 머리통(TCAM) 꽉 차서 **새로운 길을 못 외움** | 안 쓰는 쓰레기 룰들이 비싼 하드웨어 메모리를 오지게 차지하고 있음 | 안 쓰는 룰은 10초 만에 지워버리는 **Idle / Hard Timeout 빡세게 설정** | TCAM 고갈 방지 및 새로운 룰 수용 공간 확보 |
| 대장이랑 연결된 선(채널) 끊어지면 **망 전체가 먹통 됨** | OpenFlow 채널 단락 시 깡통 스위치들이 길을 못 찾아 단체로 멘붕 옴 | 연결 끊어지면 그냥 일반 라우터처럼 굴러가는 **Standalone 모드(L2/L3)로 비상 전환** | 채널 뻗어도 생존 트래픽 통신 유지 (가용성 확보) |

#### 한줄 요약

- 대장 귀찮게 징징대는 건 컷(Rate Limiting)하고, 다 쓴 룰은 바로바로 지워서 메모리(TCAM) 폭파를 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 스위치 제조사의 고질적인 벤더 종속(Lock-in)을 해결하기 위해, 중앙 SDN 컨트롤러 두뇌와 **Match-Action** 파이프라인 기반의 OpenFlow 통신 제어망 기조 확립함

#### 한줄 요약

- SDN 컨트롤러와 오픈플로우(OpenFlow)의 만남은 시스코나 주니퍼의 비싼 장비 족쇄를 풀고, 진정한 네트워크 코딩의 시대를 열어제꼈다.
