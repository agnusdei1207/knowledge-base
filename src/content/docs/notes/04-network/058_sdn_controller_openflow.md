## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **소프트웨어 정의 네트워킹(Software-Defined Networking, SDN)**: 제어 평면과 데이터 평면을 분리하는 네트워크 구조이다.
- **OpenFlow**: SDN 컨트롤러의 경로를 스위치에 흐름 규칙으로 설치하는 프로토콜이다.
- **SDN 컨트롤러**: 전역 망 상태와 정책을 바탕으로 경로와 흐름 규칙을 계산하는 중앙 제어 기능이다.

</details>

- 정의/개념: SDN 컨트롤러가 계산한 경로를 스위치에 설치하는 **OpenFlow 제어 프로토콜**이다.
- 배경/필요성: 장비별 설정은 **중앙 정책의 Match-Action 반영하기 어렵다**.

#### 한줄 요약

- 컨트롤러가 길을 정하면 OpenFlow가 스위치에 어떤 패킷을 어디로 보낼지 규칙을 전달한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **Match-Action**: 패킷 헤더가 조건과 일치하면 지정된 전달•폐기•수정 동작을 실행하는 방식이다.
- **Group•Meter 테이블**: 그룹은 복수 출력•장애 전환을 실행하고 미터는 전송률 제한•표시•폐기를 수행한다.

</details>

- 패킷 동작을 실행하는 **다단 Match-Action 테이블**이 핵심이다.
- 반응형 규칙 설치를 위한 **Table-Miss→Packet-In→Flow-Mod 절차**가 핵심이다.
- **Group•Meter 기반 경로•속도 제어와 Packet-In 폭증 위험**이 핵심이다.

#### 한줄 요약

- 스위치가 모르는 패킷을 모두 컨트롤러에 물으면 질문이 몰려 제어기가 느려질 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **OpenFlow 채널**: SDN 컨트롤러와 스위치 사이에서 제어 메시지를 교환하는 연결이다.
- **데이터 경로**: 스위치가 흐름 테이블의 규칙을 조회해 실제 패킷 동작을 실행하는 영역이다.

</details>

```text
OpenFlow 제어 구조
├─ 제어 평면
│  ├─ SDN 응용
│  ├─ SDN 컨트롤러
│  └─ OpenFlow 채널
└─ 데이터 평면
   ├─ OpenFlow 데이터 경로
   └─ 흐름•그룹•미터 테이블
```

가지의 의미: OpenFlow 제어 평면과 데이터 평면에 속한 기능을 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| SDN 응용 | 연결•보안•품질 **정책 요청** |
| SDN 컨트롤러 | 전역 상태를 이용한 **흐름 규칙** 계산 |
| OpenFlow 채널 | 컨트롤러•스위치 간 **제어 메시지** 교환 |
| 흐름•그룹•미터 테이블 | **조건•동작•경로•속도** 저장 |
| OpenFlow 데이터 경로 | 규칙 실행과 **흐름 통계** 계수 |

#### 한줄 요약

- 응용의 정책을 컨트롤러가 규칙으로 바꾸고 스위치의 여러 표가 패킷마다 동작을 실행한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **Packet-In**: Table-Miss가 발생한 패킷의 헤더와 입력 포트를 스위치가 컨트롤러에 알리는 메시지이다.
- **Flow-Mod**: 컨트롤러가 스위치의 흐름 규칙을 추가•변경•삭제하는 메시지이다.

</details>

```text
첫 데이터 패킷 입력
        │
        ▼
흐름 테이블 조회
        ├─ 일치: Match-Action 실행 후 전달
        └─ Table-Miss
              │
              ▼
        1. Packet-In
              │
              ▼
        컨트롤러의 경로•정책 계산
              │
              ▼
        2. Flow-Mod
              │
              ▼
        규칙 설치•첫 패킷 전달
```

**동작 원리**

1. **Packet-In**: Table-Miss 패킷의 헤더•입력 포트를 컨트롤러에 제공한다.
2. **Flow-Mod**: 토폴로지•정책으로 계산한 출력 동작과 제한 시간을 규칙으로 배포한다.

#### 한줄 요약

- 처음 보는 패킷은 컨트롤러에 길을 묻고 규칙이 생긴 뒤부터 스위치가 혼자 빠르게 처리한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **반응형 제어**: 첫 패킷의 Packet-In 뒤에 필요한 흐름 규칙을 설치하는 방식이다.
- **선제형 제어**: 트래픽이 도착하기 전에 반복•핵심 경로의 흐름 규칙을 미리 설치하는 방식이다.
- **삼진 내용 주소화 메모리(Ternary Content-Addressable Memory, TCAM)**: 0•1•무관 비트를 병렬 비교해 규칙을 찾는 메모리이다.

</details>

| OpenFlow 규칙 설치 | 반응형 제어 | 선제형 제어 |
|:---|:---|:---|
| 적용 기준 | 미지•단기 흐름의 **동적 제어** | 핵심•반복 경로의 **즉시 전달** |
| 핵심 특징 | **Packet-In 이후** 규칙 설치 | **트래픽 이전** 규칙 설치 |
| 한계 | 첫 패킷 지연•**컨트롤러 폭주** | TCAM 점유•**규칙 노후화** |

> 요약: 기본 규칙은 선제형, 예외 플로우는 반응형 적합이 핵심이다.

#### 한줄 요약

- 늘 쓰는 길은 미리 깔고 예외적인 길만 첫 패킷이 왔을 때 만들면 지연과 메모리를 나눌 수 있다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **유휴 제한 시간**: 일치 패킷이 없는 흐름 규칙을 제거하기까지 기다리는 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Table-Miss가 몰리면 Packet-In 처리량 초과 | **질의율 제한•기본 폐기 규칙** 적용 | 비정상 질의를 억제해 **컨트롤러 보호** |
| 모든 흐름을 선제 설치하면 TCAM 공간 고갈 | 핵심 흐름은 선제형, **예외는 반응형** 설치 | 중요 규칙을 위한 **TCAM 공간** 확보 |
| 만료되지 않은 규칙이 변경 정책과 충돌 | 유휴•고정 만료와 **규칙 회수** 검증 | 흐름 테이블의 **정책 최신성** 유지 |

#### 한줄 요약

- 모르는 패킷이 몰려도 컨트롤러 질문 수를 제한하고 나머지는 스위치에서 버린다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **규칙 설치 전략**: 핵심 경로는 선제형, 미지 흐름은 반응형으로 처리해 TCAM 사용을 조절하는 방식이다.

</details>

- 반복 핵심 경로는 **선제형**, 미지•단기 흐름은 **반응형 OpenFlow 규칙**을 선택한다.

#### 한줄 요약

- 반복되는 핵심 경로는 미리 설치하고 예외 흐름만 필요할 때 규칙을 생성해야 한다.
