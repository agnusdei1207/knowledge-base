## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **상호 전송 계층 보안(Mutual Transport Layer Security, mTLS)**: 클라이언트와 서버가 각자의 X.509 디지털 인증서와 개인키 서명을 상호 검증하여 양방향 신원을 확인하는 TLS 확장 보안 프로토콜이다.
- **전송 계층 보안(Transport Layer Security, TLS)**: 네트워크 응용 계층 간 통신 시 암호화, 데이터 무결성, 서버 신원 검증을 제공하는 전송 계층 암호화 프로토콜이다.

</details>

- 정의/개념: **mTLS(Mutual Transport Layer Security)**는 클라이언트와 서버가 각자의 디지털 인증서와 개인키 소유를 상호 검증하는 TLS 보안 통신 기법이다.
- 배경/필요성: 단방향 TLS는 서버 신원만 검증하므로, 마이크로서비스 간 통신(Zero Trust) 환경에서 불인가 호출자의 기계 신원(Machine Identity) 검증이 불가능한 한계 극복을 위해 도입된다.

#### 한줄 요약

- 통신 양 종단이 CA 발급 인증서 교환 및 개인키 서명 검증을 통해 양방향 기계 신원을 상호 증명하는 기술.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **인증서 체인(Certificate Chain)**: 종단 엔티티 인증서부터 중간 CA를 거쳐 루트 CA까지의 서명 관계를 연결한 검증 경로이다.
- **세션 키(Session Key)**: mTLS 상호 인증 완료 후 양 종단 간 전송 데이터를 대칭키 암호화 방식으로 보호하기 위해 생성되는 임시 비밀키이다.

</details>

- **양방향 신원 검증**: 서버 및 클라이언트의 인증서 체인을 동시에 검증하여 위장 기계 접속을 차단한다.
- **비대칭키 기반 서명 증명**: 개인키 노출 없이 핸드셰이크 단계의 전자서명 생성을 통해 개인키 소유권을 증명한다.
- **인증과 인가 분리**: mTLS를 통한 기계 신원 검증(Authentication) 후 서비스 접근 권한(Authorization)은 RBAC/ABAC 정책으로 별도 제어한다.

#### 한줄 요약

- 양방향 인증서·서명 검증으로 기계 신원을 입증하고 상호 암호화 세션 키 생성 후 별도 권한 인가 정책을 적용함.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **인증기관(Certificate Authority, CA)**: 공개키 인증서를 발급, 서명, 폐기 관리하며 신뢰 체인의 최상위 신뢰점(Trust Anchor)을 제공하는 기관이다.
- **신뢰 저장소(Trust Store)**: 상대방 인증서 체인의 유효성을 검증하기 위해 신뢰하는 루트 및 중간 CA 인증서를 보관하는 보안 저장소이다.

</details>

```text
상호 전송 계층 보안 신뢰 경계
├── 인증기관(CA)
├── 클라이언트 인증서·개인키
├── 서버 인증서·개인키
├── 양측 신뢰 저장소
└── 대칭 세션 키
```

선의 의미: 공통 인증기관(CA)의 신뢰를 바탕으로 클라이언트와 서버가 각자의 인증서·개인키를 내세워 신뢰 저장소 기반 상호 검증을 완료하고 대칭 세션 키 보안 경계를 형성하는 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 인증기관(CA) | 종단 인증서 발급·서명 및 신뢰 체인 최상위 신뢰점 제공 |
| 클라이언트 인증서·키 | 클라이언트 기계 신원 및 개인키 소유권 서명 증명 |
| 서버 인증서·키 | 서버 기계 신원 및 개인키 소유권 서명 증명 |
| 양측 신뢰 저장소 | 검증 허용 대상 CA 인증서 체인 보관 및 유효성 검증 |
| 대칭 세션 키 | 상호 인증 완료 후 세션 데이터 고속 암호화·복호화 수행 |

#### 한줄 요약

- 공통 CA 기반의 신뢰 저장소를 통해 양측 인증서와 개인키 소유를 검증하고 암호화 세션 키를 생성하는 구조.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **전자서명(Digital Signature)**: 송신자의 개인키로 암호화한 서명값을 수신자가 공개키로 검증하여 데이터 무결성과 비부인성을 보장하는 기술이다.
- **서버 인증 증명(Server Authentication Proof)**: 서버가 자신의 인증서 체인과 난수 기반 전자서명을 클라이언트에 제공하여 신원을 입증하는 절차이다.
- **서버 체인 검증(Server Chain Verification)**: 클라이언트가 신뢰 저장소의 CA 서명, 유효 기간, CRL/OCSP 상태를 대조해 서버 인증서를 검증하는 과정이다.
- **클라이언트 인증 요청(Certificate Request)**: 서버가 핸드셰이크 중 클라이언트에게 허용 CA 목록과 함께 인증서 제출을 요청하는 절차이다.
- **클라이언트 인증 증명(Client Certificate Verify)**: 클라이언트가 인증서 체인과 Certificate Verify 메시지 서명을 서버로 전송하는 절차이다.
- **클라이언트 체인 검증(Client Chain Verification)**: 서버가 신뢰 저장소를 사용해 클라이언트 인증서 체인과 서명 유효성을 검증하는 과정이다.

</details>

```text
전송 계층 보안 연결 요청
      |
      v
서버: 1. 서버 인증 증명 (인증서 체인 전송)
      |
      v
클라이언트: 2. 서버 체인 검증
      |
      +-- 검증 실패 ---- 연결 종료
      |
      `-- 검증 성공
             |
             v
서버: 3. 클라이언트 인증 요청
             |
             v
클라이언트: 4. 클라이언트 인증 증명 (인증서 체인 및 서명 전송)
             |
             v
서버: 5. 클라이언트 체인 검증
             |
             +-- 검증 실패 ---- 연결 종료
             `-- 검증 성공 ---- mTLS 상호 인증 완료 및 세션 키 생성
```

### 동작 원리

1. **서버 인증 증명**: 서버가 자신의 인증서 체인과 난수 기반 전자서명을 클라이언트에 전송한다.
2. **서버 체인 검증**: 클라이언트가 신뢰 CA 체인, 만료 여부, 폐기 상태(CRL/OCSP)를 확인한다.
3. **클라이언트 인증 요청**: 서버가 클라이언트에게 제출 허용 CA 목록을 전달하며 인증서 제출을 요구한다.
4. **클라이언트 인증 증명**: 클라이언트가 인증서 체인과 핸드셰이크 메시지 서명(Certificate Verify)을 서버에 제출한다.
5. **클라이언트 체인 검증**: 서버가 클라이언트 인증서 유효성과 서명을 검증하여 상호 인증을 완료하고 세션 키를 생성한다.

#### 한줄 요약

- 서버 검증 후 클라이언트 인증 요청에 따라 인증서 및 서명을 제출·검증하여 상호 인증 완료 및 세션 키 형성.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단방향 전송 계층 보안(One-Way Transport Layer Security, One-Way TLS)**: 서버만 인증서를 제시하고 클라이언트는 서버 신원만 검증한 채 세션 키를 형성하는 일반적인 TLS 방식이다.

</details>

| TLS 인증 방식 | **mTLS (상호 TLS)** | **단방향 TLS (One-Way TLS)** |
|:---|:---|:---|
| 적용 기준 | 마이크로서비스 간(M2M), Zero Trust 내 내부 통신 | 불특정 다수 웹 사용자 대상 공개 서비스 |
| 핵심 특징 | 서버 및 클라이언트 양방향 인증서·서명 검증 | 서버 인증서만 검증, 클라이언트는 무인증 |
| 한계 | 인증서 주기적 발급·회전(Rotation) 등 운영 복잡성 증가 | 클라이언트 기계 신원 검증 불가능 |

> 요약: 서비스 간 M2M 통신 및 Zero Trust 환경에서는 mTLS, 공개 웹 서비스에는 단방향 TLS 적용.

#### 한줄 요약

- 단방향 TLS는 서버 신원만 확인하는 반면 mTLS는 클라이언트 기계 신원까지 상호 검증하여 높은 보안성 제공.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **인증서 폐기 목록(Certificate Revocation List, CRL)**: 인증기관이 만료 전 실효된 인증서 목록을 생성하여 서명·배포하는 폐기 검증 목록이다.
- **최소 권한 원칙(Principle of Least Privilege, PoLP)**: 사용자 또는 기계에 업무 수행에 필요한 최소한의 접근 권한만 부여하는 보안 원칙이다.

</details>

| 문제점 | 대응 대책 | 기대 효과 |
|:---|:---|:---|
| 인증서 만료에 따른 통신 장애 발생 | Automated Certificate Management Environment(ACME) 기반 자동 발급 및 회전 | 만료 장애 방지 및 관리 공수 절감 |
| 탈취된 인증서의 부적절한 승인 | 단기 인증서(Short-Lived Cert) 도입 및 CRL/OCSP Real-time 검증 | 탈취 인증서 즉시 차단 및 신뢰성 확보 |
| 양 종단 간 CA 신뢰 저장소 불일치 | 서비스 메쉬(Service Mesh) 기반 신뢰 저장소 버전 중앙 관리 | 인증 실패 감소 및 일관된 보안 정책 유지 |
| mTLS 통과를 권한 승인으로 오해 | SPIFFE/SPIRE 기반 신원 식별 후 RBAC/ABAC 기반 권한 통제 연동 | 신원 검증과 인가 분리로 최소 권한 원칙 달성 |

#### 한줄 요약

- ACME 자동 회전, CRL/OCSP 검증, 서비스 메쉬 중앙 관리 및 RBAC 연동으로 mTLS의 운영 복잡성과 보안 리스크 해소.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **인증과 인가 분리(Authentication/Authorization Separation)**: mTLS를 통한 기계 신원 인증(Authentication)과 서비스 접근 권한 인가(Authorization)를 엄격히 분리 관리하는 보안 원칙이다.

</details>

- Zero Trust 네트워크 아키텍처 구축 시 **mTLS 기반 양방향 기계 신원 검증**과 **SPIFFE/RBAC 연동 인가 통제 체계** 병행 구축 필수.

#### 한줄 요약

- mTLS 기반 기계 신원 상호 검증 체계 및 최소 권한 통제 연동 구현 필수.
