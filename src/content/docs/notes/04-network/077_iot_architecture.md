## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **사물인터넷 (IoT)**: 온도계, 가스 밸브, 자판기 같은 단순한 '사물'에 통신 칩을 달아서, 중앙 플랫폼과 데이터를 주고받고 원격으로 기계 동작을 껐다 켰다 하는 전 지구적 연결망이다.
- **IoT 아키텍처 (운영 구조)**: 현장의 멍청한 센서(장치)부터 중간 통역사(게이트웨이/엣지), 그리고 최종 지휘 통제실(플랫폼)까지 데이터가 올라가고 명령이 내려오는 뼈대 설계도다.

</details>

- 정의: **IoT 아키텍처**는 사물인터넷의 센서(장치)부터 게이트웨이, 엣지, 플랫폼까지 데이터 수집과 기기 제어, 수명 관리를 엮어낸 **종합 운영 구조**다.
- 배경: 집에 있는 에어컨 1~2대면 그냥 폰으로 연결하면 되지만, 전국에 깔린 스마트 미터기가 수백만 개로 늘어나면 개별 관리가 불가능해서, **수집/통역/분석/제어의 역할을 층(Layer)별로 나눈 체계적인 아키텍처가 필수다.**

#### 한줄 요약

- 센서값의 이동 경로와 현장 제어, 장치 등록부터 폐기까지의 역할을 클라우드와 엣지 장비로 나눠서 팩트 관리하는 설계도다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수명주기 추적 (Lifecycle Management)**: 센서가 공장에서 태어나(등록) 와이파이 비번을 받고(인증), 쓰다가 펌웨어 업데이트(갱신)를 받고, 망가지면 폐기되는 전 과정을 중앙 클라우드에서 멱살 잡고 관리하는 체계다.

</details>

- **역할 분담의 미학**: 센서는 측정만 하고, 게이트웨이는 통신을 통역하고, 엣지는 급한 불 끄고, 플랫폼은 빅데이터 분석을 하는 철저한 4단계 역할 분담 구조다.
- **수명주기 풀 제어 (Lifecycle)**: 센서 하나하나의 등록부터 보안 인증, 해킹 방어, 원격 펌웨어 갱신, 수명 종료 시 권한 회수(폐기)까지 플랫폼이 요람에서 무덤까지 팩트 통제한다.
- **단방향 수집을 넘어선 양방향 제어**: 옛날엔 센서값만 쭉 빨아들였다면, 이제는 중앙에서 분석 후 "위험하다, 공장 밸브 잠가라!" 하고 역으로 엑추에이터 제어 명령을 내리는 게 핵심이다.

#### 한줄 요약

- 데이터는 위로 올리고 제어 명령은 아래로 내리며, 100만 개 센서의 생로병사를 중앙에서 한 방에 관리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IoT 플랫폼 (Platform)**: 전 세계 흩어진 수백만 개 센서들의 등록 명부, 데이터 로그, 펌웨어 버전을 한 방에 통합 관리하는 AWS IoT 같은 중앙 지휘소(클라우드)다.
- **게이트웨이 (Gateway)**: 블루투스, 지그비(Zigbee) 같은 저전력 외계어를 쓰는 멍청한 센서들의 말을 모아서, 인터넷 표준어(IP)로 번역해 플랫폼에 쏴주는 현장 통역사다.
- **엣지 (Edge)**: 클라우드까지 명령이 갔다 오면 늦으니까, 공장 로봇 팔 같은 건 현장에서 1ms 만에 바로 판단하고 멈춰버리는 현장 소장님(초소형 서버)이다.

</details>

```text
[ IoT 생태계 팩트 폭행 구조 ]

[ 1. 클라우드 플랫폼 / 응용 ] ── (수백만 개 데이터 모아서 빅데이터 분석하고 펌웨어 쏨)
      │
      ▼
[ 2. 엣지 (Edge) 컴퓨팅 ] ── (인터넷 끊겨도 "어 공장 불났네? 일단 밸브 잠가!" 하고 현장 제어함)
      │
      ▼
[ 3. 게이트웨이 (Gateway) ] ── (블루투스, 지그비 싹 다 모아서 Wi-Fi나 LTE로 번역해 줌)
      │
      ▼
[ 4. 디바이스 (Sensors/Actuators) ] ── (현장에서 온도 재고 모터 돌리는 말단 노가다꾼)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **응용 / 플랫폼** | 장치 명부 관리, 데이터 분석, **원격 업데이트 쏘는 중앙 지휘 통제실** | Cloud Platform |
| **엣지 (Edge)** | 통신 끊겨도 멈추면 안 되는 **실시간 현장 제어 1차 방어선 (현장 소장)** | Edge Computing |
| **게이트웨이** | 블루투스/지그비 외계어를 **인터넷 통신망(IP)으로 번역해 주는 통역사** | IoT Gateway |
| **디바이스** | 센서로 정보 캐고 액추에이터로 **모터 돌리는 말단 현장 기기** | Device / Sensor |

#### 한줄 요약

- 디바이스가 캔 데이터를 게이트웨이가 통역하고, 급한 건 엣지가 제어하며, 플랫폼이 전체를 지휘한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **텔레메트리 (Telemetry)**: 센서가 "지금 온도 30도, 배터리 50%" 하고 주기적으로 플랫폼에 쏴주는 생사 보고서(데이터 측정값)다.
- **OTA (무선 업데이트)**: 스마트폰 펌웨어 업데이트하듯, 산꼭대기 센서에 케이블 안 꽂고 공중파(통신망)로 소프트웨어 싹 갈아엎는 마법의 원격 갱신 기술이다.
- **이벤트 동기화**: 통신 끊겼을 때 센서가 기기 버퍼에 데이터를 쌓아뒀다가, 연결 복구되면 시간 순서대로 안 꼬이게 쫙 밀어 올려주는 팩트 정렬 기능이다.

</details>

```text
[ IoT 생애 주기 및 데이터 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [장치 등록 및 보안 인증]  │
│ (플랫폼: 너 내 허가받은 센서 맞네? 인증서 박고 통신 뚫어줄게)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [텔레메트리 수집 및 동기화]
│ (디바이스: 온도 35도 돌파! 데이터 쏩니다. 끊기면 모았다 쏠게요!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [빅데이터 분석 및 제어 요청]
│ (플랫폼: 온도 너무 높고 패턴 이상하네. 공장 에어컨 틀어라!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [제어 명령 하달 및 액추에이터 실행]
│ (디바이스: 넵! 릴레이 스위치 붙여서 에어컨 켭니다!)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [OTA 펌웨어 갱신 및 수명 폐기]
│ (플랫폼: 보안 패치 떴다! 펌웨어 공중에서(OTA) 일괄 쏴줌)
└──────────────────────────────┘
```

### 동작 원리

1. 장치 등록: 식별자, 소유자 정보, 보안 자격 증명을 엮어 클라우드 플랫폼에 기기를 정식 **등록**함.
2. 텔레메트리 수집/동기화: 센서 측정값에 시간표를 찍어 올리고, 통신 단절 시 쌓인 데이터 중복을 제거해 **동기화**함.
3. 데이터 분석: 플랫폼이 올라온 텔레메트리를 분석해 룰(Rule)에 맞으면 엑추에이터에 **제어 명령**을 하달함.
4. 명령 실행: 현장 기기가 수신한 명령이 안전한지 검증 후 모터/밸브 등을 작동시킴.
5. 수명 갱신: 플랫폼에서 전 세계 기기들한테 일괄적으로 **OTA(무선 업데이트)** 를 쏘거나, 기기 폐기 시 보안 토큰을 회수함.

#### 한줄 요약

- 등록 $\to$ 데이터 쏘기 $\to$ 분석 후 명령 때리기 $\to$ 원격 업데이트의 반복된 사이클이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **게이트웨이 중계형**: 블루투스 센서처럼 인터넷 직접 연결이 안 되는 놈들 사이에서, 게이트웨이가 데이터를 싹 쓸어 모아 대신 클라우드에 보고해 주는 구조다.
- **엣지 협업형**: 클라우드 통신 지연(Delay)을 못 기다리는 공장 로봇을 위해, 현장 서버(엣지)가 직접 통제권을 갖는 진화된 구조다.

</details>

| 비교 항목 | **게이트웨이 중계형 (번역가 낌)** | **엣지 협업형 (현장 소장 낌)** | **직접 연결형 (다이렉트 IP)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | 멍청한 센서들 말 모아서 **통역사가 대신 보고함** | 클라우드 안 가고 **현장 소장이 0.1초 만에 바로 지시함** | 센서가 똑똑해서 **본사(클라우드)랑 직통으로 통화함** |
| 장착 환경 | 블루투스, 지그비 등 **저전력 이기종 센서가 판칠 때** | 스마트 공장, 자율주행 등 **1ms의 지연도 용납 안 될 때** | 센서 자체가 Wi-Fi/LTE 칩 내장한 **스마트 IP 기기일 때** |
| 최고 장점 | 배터리 작아도 게이트웨이 하나로 수만 개 센서 연결 가능 | 클라우드 망 터져도 **현장 기계가 안 멈추고 자율 제어함** | 구조가 심플하고 그냥 라우터/공유기만 있으면 끝남 |
| 치명적 한계 | 게이트웨이 전원 꺼지면 **밑에 달린 센서 싹 다 통신 두절됨** | 현장 엣지 서버랑 본사 플랫폼 상태 동기화 꼬이면 지옥 됨 | 센서마다 5G 유심 꽂고 IP 주소 할당하려면 유지비 박살 남 |

#### 한줄 요약

- 이기종은 게이트웨이, 끊기면 죽는 건 엣지, 똑똑한 센서는 직접 연결형으로 아키텍처를 짠다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장치 벽돌화 (Bricking)**: OTA 업데이트를 공중에서 쏘다가 통신이 끊겨 펌웨어가 꼬이면, 산꼭대기에 있는 비싼 센서가 그냥 부팅 안 되는 쇳덩어리(벽돌)가 되어버려 관리자가 직접 등산해야 하는 대참사다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 클라우드 통신 끊겼더니 **스마트 공장 전체가 뻗어버림** | 제어 로직을 100% 클라우드에 의존해서, 인터넷이 끊기자 기계 뇌가 마비됨 | 클라우드 말고 **현장 엣지(Edge) 장비에 비상 안전 제어 로직(버퍼) 깔아둠** | 회선 단절돼도 현장 작업 연속성 챙기고 공장 안 터짐 |
| 통신 복구됐는데 **센서 과거 데이터가 짬뽕 돼서 들어감** | 끊긴 동안 기기에 모아둔 데이터랑 최신 데이터가 순서 없이 섞여서 들어가 버림 | 시각(Timestamp) 팩트 체크해서 **시간 순서대로 재정렬하는 멱등 동기화 돌림** | 통계 상태 꼬이는 거 막고 오작동/이중 실행 원천 차단 |
| 펌웨어 업데이트 쐈는데 **센서 1만 개가 부팅 안 되는 벽돌 됨** | 업데이트 파일 깨졌는데 자체 롤백 기능이 없어서 OS 부팅이 아예 안 됨 | 100개씩 간 보며 쏘는(Canary) **단계 배포랑 실패 시 구버전 자동 롤백 필수로 켬** | 사람이 산꼭대기/전봇대 올라가서 수동 초기화하는 지옥 회피 |

#### 한줄 요약

- 통신 단절에 대비해 현장(엣지)에 비상 통제권 남겨두고, 무선 업데이트(OTA) 할 땐 벽돌 될까 봐 무조건 롤백 켜라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 수많은 파편화된 IoT 기기를 효율적으로 제어하기 위해, **현장(엣지)과 플랫폼(클라우드)의 역할 분담**, **이기종 게이트웨이 중계**, **전 수명주기 OTA 관리** 기조 확립함

#### 한줄 요약

- IoT 아키텍처는 센서 백만 개가 뿜는 데이터를 쓸모없는 쓰레기에서 돈이 되는 정보로 정제하고 통제하는 거대한 신경망 설계도다.
