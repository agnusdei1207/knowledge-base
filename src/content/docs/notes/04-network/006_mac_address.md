## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MAC Address (매체 접근 제어 주소)**: 데이터링크 계층(L2)에서 네트워크 인터페이스 카드(NIC)를 식별하기 위해 부여된 48비트(6옥텟) 물리적 하드웨어 주소.
- **CAM Table (Content Addressable Memory)**: L2 스위치가 프레임의 출발지 MAC 주소를 학습하여 특정 포트 번호와 매핑 저장하는 고속 조회 메모리 테이블.

</details>

- 정의/개념: 로컬 네트워크(LAN) 세그먼트 내에서 노드 간 프레임 전송을 위해 네트워크 인터페이스에 부여된 **48비트(6옥텟) 물리적 하드웨어 주소 체계**
- 배경/필요성: L3 논리적 IP 주소만으로는 **동일 링크 상의 실제 물리 하드웨어 인터페이스를 식별할 수 없어 L2 프레임 전달 및 스위칭 불가**하므로, 인터페이스마다 전역 유일한 48비트 하드웨어 주소를 새겨 링크 구간의 수신자 판별을 L3 경로 계산과 분리하고 스위치가 학습만으로 전달하게 할 식별 계층의 필요

#### 한줄 요약
- MAC 주소는 제조 시점에 고정되어 위치 정보를 담지 못하므로 링크 내부 식별에만 쓰이고, 망을 넘는 경로 결정은 위치를 반영해 집약 가능한 IP 주소에 맡긴다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **I/G Bit (Individual/Group Bit)**: MAC 주소의 첫 번째 옥텟 최하위 비트(LSB)로, 유니캐스트(0)와 멀티캐스트/브로드캐스트(1)를 판정.
- **U/L Bit (Universal/Local Bit)**: 첫 번째 옥텟의 1번 비트로, 제조사 출하 전역 고유 주소(UAA, 0)와 가상화/로컬 관리 주소(LAA, 1)를 구분.

</details>

- 48비트(6바이트)를 16진수 표기법(`00:1A:2B:3C:4D:5E`)으로 구조화하여 표현
- 최하위 **I/G 비트(Individual/Group)**를 통해 유니캐스트와 멀티캐스트 프레임 즉각 식별
- 1번 **U/L 비트(Universal/Local)**를 통해 제조사 전역 주소(UAA)와 가상화 주소(LAA) 판정

#### 한줄 요약
- 48비트 16진수 표기, I/G 전송 판정, U/L 관리 주체 구분을 통해 L2 물리 주소를 식별한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **OUI (Organizationally Unique Identifier)**: IEEE가 시스코, 인텔 등 하드웨어 제조사에 부여하는 상위 24비트 벤더 고유 코드.

</details>

```text
[48비트 MAC 주소]
|-- 상위 24비트 OUI
|   |-- I/G 비트
|   `-- U/L 비트
`-- 하위 24비트 인터페이스 식별자
```

선의 의미: 계층 및 상위 24비트 OUI 내 첫 번째 옥텟의 제어 비트와 하위 24비트 장치 일련번호로 구성되는 구조

| 구성요소 | 책임 |
|:---|:---|
| **OUI** | 제조사 식별용 상위 24비트 제공 |
| **I/G 비트** | 개별·그룹 주소 판정 |
| **U/L 비트** | 전역·로컬 관리 주소 판정 |
| **인터페이스 식별자** | 인터페이스별 하위 비트 제공 |

#### 한줄 요약
- 상위 24비트를 IEEE가 관리하는 OUI로 떼어 전역 중복 방지 책임을 제조사 밖으로 옮기고, 첫 옥텟의 제어 비트가 주소 안에 전송 유형과 관리 주체를 새겨 별도 조회를 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **CAM 테이블 포워딩 5단계**: 프레임 수신 $\to$ 출발지 MAC 학습 $\to$ 목적지 CAM 조회 $\to$ 포워딩 또는 플러딩 $\to$ 에이징 타이머 갱신.

</details>

```text
[프레임 인입]
      |
1. 출발지 학습
      |
2. 목적지 조회
   /       \
 알려짐    미등록
  |          |
3. 선별 전송 3. 플러딩
   \       /
   [프레임 송출]
```

- 1. 출발지 학습: MAC·포트 매핑과 에이징 갱신
- 2. 목적지 조회: **CAM 테이블**에서 출력 포트 탐색
- 3. 선별 전송/플러딩: 등록 여부별 프레임 전달

#### 한줄 요약
- CAM에 등록된 목적지는 한 포트로만 나가지만 미등록 목적지는 플러딩으로 전 포트 대역폭을 소모하므로, 학습 실패의 대가가 그대로 링크 낭비로 돌아온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **UAA (Universally Administered Address)** vs **LAA (Locally Administered Address)**: 벤더사 고정 하드웨어 주소(UAA)와 가상 머신/소프트웨어 정의 주소(LAA).

</details>

| 비교 항목 | 전역 관리 주소 (UAA) | 로컬 관리 주소 (LAA) |
|:---|:---|:---|
| 할당 주체 | 제조사 | 관리자·가상화 플랫폼 |
| U/L 비트 | **0** | **1** |
| 적용 영역 | 물리 NIC | 가상 NIC·컨테이너 인터페이스 |
| 주의점 | 제조사 할당 범위의 중복 관리 | 로컬 도메인 내 중복 방지 |

#### 한줄 요약
- 하드웨어 고정 주소인 UAA와 가상화 환경에서 소프트웨어로 동적 부여하는 LAA로 구분된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MAC Flooding Attack**: 공격자가 수만 개의 위조된 MAC 주소를 스위치로 난사하여 CAM 테이블을 고갈시키고, 스위치를 모든 트래픽이 브로드캐스팅되는 허브처럼 동작하게 만들어 패킷을 도청하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위조 MAC 프레임 폭주로 스위치 CAM 테이블 고갈(MAC Flooding) | **스위치 포트별 `최대 MAC 학습 수 제한(Port Security)` 및 Sticky 설정** | CAM 오버플로우 방지 및 포트 자동 셧다운 |
| 공격자의 인가 호스트 MAC 스푸핑 및 L2 트래픽 가로채기(MITM) | **`동적 ARP 검사(DAI) 및 DHCP Snooping` 바인딩 테이블 연동** | 비인가 변조 프레임 즉각 드롭 |
| 비인가 단말의 무단 유선 LAN 접속으로 인한 사내망 침해 | **스위치 포트 수준의 `IEEE 802.1X EAP/RADIUS 기반 포트 인증` 강제** | 물리 MAC 주소 위조 원천 차단 |
| 가상화 VM/컨테이너 대량 생성 시 LAA MAC 주소 중복 충돌 | **IPAM 및 클라우드 오케스트레이터의 `고유 MAC 풀 자동 관리`** | L2 세그먼트 내 MAC 충돌 방지 |

#### 한줄 요약
- Port Security, DAI/DHCP Snooping, IEEE 802.1X 인증, MAC 풀 관리로 운영한다.

## Ⅶ. 결론

- 단말 제한은 **Port Security**, 사용자 인증은 802.1X 적용

#### 한줄 요약
- MAC 주소는 48비트 구조와 I/G, U/L 제어 비트를 통해 LAN 내 프레임 전달을 수행하며, Port Security 및 802.1X 인증과 결합하여 보안성을 보장하는 핵심 L2 기술이다.
