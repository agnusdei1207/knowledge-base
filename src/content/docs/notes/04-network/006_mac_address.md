## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MAC 주소(MAC Address)**: L2 랜카드(NIC)에 공장 출고 때부터 인두로 지져놓은 48비트 하드웨어 주민번호이다.
- **IP 주소(IP Address)**: 이사 가면 바뀌는 주소(논리)라면, MAC 주소는 평생 안 바뀌는 주민번호(물리)로 같은 방(동일 링크) 안에서 컴퓨터를 찾는 데 쓴다.

</details>

- 정의: 데이터링크 계층(L2)에서 동일 네트워크 내의 랜카드를 식별하기 위한 **48비트 물리적 주소**
- 배경: IP 주소만으로는 바로 옆 장비의 랜카드가 어디 있는지 몰라 **이더넷 프레임 전달이 불가능했기 때문** #### 한줄 요약

- 같은 방(랜선) 안에서 "너 몇 번 랜카드냐" 하고 기계를 직접 부를 때 쓰는 48비트 고유 번호다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **옥텟(Octet)**: 48비트 MAC 주소를 8비트(1바이트)씩 잘라놓은 6개의 덩어리이다.
- **I/G 비트(Individual/Group Bit)**: 첫 덩어리 끝에 붙어 "나 혼자(유니캐스트) 받을지, 다 같이(멀티캐스트) 받을지" 결정하는 깃발이다.
- **U/L 비트(Universal/Local Bit)**: "이 주소가 공장 정품(UAA)인지, 소프트웨어로 조작한 임시(LAA)인지" 판별하는 깃발이다.

</details>

- 48비트(6개 **옥텟**)를 16진수 표기법(예: `00:1A:2B:3C:4D:5E`)으로 구조화.
- **I/G 비트(개별/그룹 비트)** 를 통해 유니캐스트와 멀티캐스트 프레임을 수신단 하드웨어에서 즉각 분기 처리.
- **U/L 비트(전역/로컬 비트)** 를 통해 제조사 정품 주소와 소프트웨어 생성 가상 주소를 구분.

#### 한줄 요약

- 48비트를 6칸으로 나누고, I/G 비트와 U/L 비트로 통신 방식과 정품 여부를 가려낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **조직 고유 식별자(OUI)**: MAC 주소 앞쪽 24비트로, IEEE가 시스코나 인텔 같은 제조사에게 "넌 이 번호 써라" 하고 찍어준 회사 식별 코드이다.
- **인터페이스 식별자(Interface Identifier)**: MAC 주소 뒤쪽 24비트로, 제조사가 랜카드를 찍어낼 때마다 1씩 올려서 중복 안 되게 박아넣는 시리얼 번호이다.

</details>

```text
[ 48비트 MAC 주소 직관적 비교 구조 ]

[ ─── 상위 24비트 (OUI) ─── ] [ ─ 하위 24비트 (시리얼) ─ ]
[  1바이트 ][  2바이트 ][  3바이트 ] [  4바이트 ][  5바이트 ][  6바이트 ]
 000000[U/L][I/G] ─▶ 제어 비트는 1바이트 꼬리에 붙음
```

| 구성요소 | 비트 범위 | 직관적 비교 역할 | 비고 |
|:---|:---|:---|:---|
| **조직 고유 식별자 (OUI)** | 앞 24비트 | IEEE가 "이건 삼성 랜카드네" 하고 제조사를 인증해 주는 고유 코드 | 상위 3옥텟 |
| **I/G 비트** | 1옥텟 8번 비트 | 0이면 나 혼자(유니캐스트), 1이면 단체(멀티/브로드캐스트) 송신 | 전송 범위 판단 |
| **U/L 비트** | 1옥텟 7번 비트 | 0이면 공장 정품 주소(UAA), 1이면 조작/가상 주소(LAA) | 관리 주체 판별 |
| **인터페이스 식별자** | 뒤 24비트 | 공장에서 카드 찍어낼 때마다 하나씩 올려서 박는 시리얼 번호 | 하위 3옥텟 |

#### 한줄 요약

- 앞 24비트는 제조사 이름표고, 뒤 24비트는 겹치지 않게 찍어낸 제품 일련번호다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **출발지 MAC 학습(Source MAC Learning)**: 스위치가 보낸 놈(출발지 MAC)을 보고, "1번 포트에 철수가 있구나" 하고 장부(CAM 테이블)에 적는 과정이다.
- **목적지 MAC 조회(Destination MAC Lookup)**: 스위치가 장부를 뒤져서 받을 놈(목적지 MAC)이 몇 번 포트에 있는지 찾는 과정이다.
- **플러딩(Flooding)**: 장부에 받을 놈이 없으면 "누군지 몰라! 다 받아라!" 하고 모든 구멍으로 패킷을 쏴버리는 무식한 전파이다.

</details>

```text
[ L2 스위치 MAC 주소 처리 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. 이더넷 프레임 스위치 유입 │
│ (A가 B에게 짐을 보냄)        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 출발지 주소 학습          │
│ (장부에 A MAC = 1번 포트 기록) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 목적지 주소 조회          │
│ (장부에 B MAC이 있는지 검색)   │
└────────┬─────┬─────────────┘
         │     │
   [장부에 있음] [장부에 없음]
         ▼     ▼
┌────────────┐ ┌──────────────┐
│ 4. 단일 전달 │ │ 4. 플러딩    │
│ (B 포트로 쏨)│ │ (다 전송함)  │
└────────────┘ └──────────────┘
```

### 동작 원리

1. 프레임 유입: 스위치 포트에 프레임이 꽂힘.
2. 출발지 주소 학습: 스위치가 보낸 놈 MAC을 포트 번호와 함께 CAM 테이블에 씀.
3. 목적지 주소 조회: 받을 놈 MAC이 테이블에 있는지 검색함.
4. 단일 포트 전달(Unicast): 테이블에 있으면 그 포트로만 정확하게 1:1로 쏨.
5. 플러딩(Flooding): 테이블에 없으면 들어온 포트 빼고 나머지 포트로 다 전송함.

#### 한줄 요약

- 보낸 놈은 장부에 적어두고(학습), 받을 놈은 장부 보고 찾아서 보내거나(단일 전달) 모르면 다 쏴버린다(플러딩).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **UAA(전역 관리 MAC)**: 세상에 단 하나뿐인, 공장에서 반도체 롬에 지져버린 영구적인 진짜 하드웨어 MAC 주소이다.
- **LAA(로컬 관리 MAC)**: 가상 머신(VM)을 만들거나 해커가 주소를 숨길 때 소프트웨어로 덮어씌운 임시 가짜 주소이다.

</details>

| 구분 | **전역 관리 MAC (UAA)** | **로컬 관리 MAC (LAA)** |
|:---|:---|:---|
| 주소 생성 주체 | 하드웨어 제조사 (IEEE OUI 룰 지켜서 만듦) | 하이퍼바이저(VM), OS 관리자, 무선 보안 모듈 |
| U/L 비트 | **0** (전 세계 유일 보장) | **1** (이 동네에서만 씀) |
| 활용 분야 | 물리적인 랜카드(NIC), 이더넷 스위치 하드웨어 포트 | VM(가상머신), 컨테이너, **MAC 스푸핑(변조)** |
| 장단점 | 세계적 고유성 보장 / **주소 추적으로 프라이버시 노출** | 주소를 마음대로 찍어냄 / **IP처럼 중복될 위험 존재** |

#### 한줄 요약

- UAA는 공장에서 찍어낸 찐 주민번호고, LAA는 소프트웨어로 위조한 가짜 신분증이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MAC 스푸핑(MAC Spoofing)**: 해커가 자기 주소를 사장님 컴퓨터 주소로 조작해서, 스위치 장부를 꼬이게 만들고 남의 패킷을 훔쳐보는 사기 수법이다.
- **IEEE 802.1X**: 조작하기 쉬운 MAC 주소를 믿지 않고, 랜선 꽂았을 때 진짜 ID/비밀번호(인증서)를 요구하는 포트 보안 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 해커가 **MAC 스푸핑** 기반 주소를 조작해서 남의 패킷을 훔쳐봄 | 스위치에 **포트 보안(Port Security) 및 DAI** 적용 | 위조 MAC 프레임 드롭 및 불량 포트 셧다운 |
| 좀비 PC가 가짜 MAC을 1초에 만 개씩 쏴서 스위치 장부 터짐 | 스위치 포트별로 학습하는 **MAC 개수 제한(Sticky MAC)** | 스위치 메모리 고갈 및 전 구간 플러딩 마비 예방 |
| 외부인이 몰래 빈 랜선 포트에 노트북 꽂아서 사내망 뚫음 | MAC 주소 믿지 말고 **IEEE 802.1X** 기반 사용자 인증 도입 | 무단 기기(비인가 디바이스) 네트워크 접근 원천 차단 |

#### 한줄 요약

- MAC은 위조하기 너무 쉬우니, 802.1X 인증을 걸고 포트당 MAC 개수를 묶어놔라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **포트 보안(Port Security)**: 스위치 포트에 "이 MAC 주소만 통과시켜!" 하거나 "MAC 3개까지만 받아!" 하고 자물쇠를 채우는 L2 스위치 방어 기술이다.

</details>

- **통제 선택** 원칙에 따라, 위조가 쉬운 MAC 주소의 한계를 극복하기 위해 고정 장비는 **포트 보안** 기반 막고 사용자 기기는 **802.1X** 인증을 결합하는 기조 확립함

#### 한줄 요약

- MAC 주소는 뚫리기 쉬운 철조망이니 802.1X라는 콘크리트 벽을 같이 세워야 한다.
