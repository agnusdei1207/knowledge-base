## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MAC 주소(Media Access Control Address)**: 데이터링크 계층(OSI L2)에서 네트워크 인터페이스 컨트롤러(NIC)를 식별하기 위해 부여된 48비트(6바이트) 고유 하드웨어 주소.
- **이더넷 프레임(Ethernet Frame)**: 데이터링크 계층에서 송수신되는 기본 전송 단위로, 헤더에 출발지 MAC과 목적지 MAC 주소를 포함.

</details>

- 정의/개념: 로컬 영역 네트워크(LAN) 세그먼트 내에서 노드 간 프레임 전송을 위해 네트워크 인터페이스에 부여된 **48비트 물리적 주소 체계**
- 배경/필요성: L3 논리적 IP 주소만으로는 동일 링크 상의 실제 물리 하드웨어 인터페이스를 특정할 수 없어 L2 프레임 전달 불가

#### 한줄 요약
- 동일 네트워크 세그먼트 내의 노드 식별과 L2 프레임 포워딩을 위한 48비트 고유 물리 주소다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **I/G 비트(Individual/Group Bit)**: MAC 주소의 첫 번째 옥텟 최하위 비트(LSB)로, 목적지 주소가 단일 호스트(Unicast, 0)인지 그룹 주소(Multicast/Broadcast, 1)인지 식별.
- **U/L 비트(Universal/Local Bit)**: MAC 주소의 첫 번째 옥텟 하위 두 번째 비트로, IEEE에서 할당한 전역 고유 주소(UAA, 0)인지 관리자가 설정한 로컬 관리 주소(LAA, 1)인지 식별.

</details>

- 48비트(6옥텟)를 16진수 표기법(예: `00:1A:2B:3C:4D:5E`)으로 구조화하여 표현
- **I/G 비트** 를 통해 유니캐스트와 멀티캐스트 프레임을 수신 하드웨어 계층에서 즉각 판정
- **U/L 비트** 를 통해 제조사 공인 전역 주소(UAA)와 가상화/소프트웨어 정의 로컬 주소(LAA) 구분

#### 한줄 요약
- 상위 OUI와 하위 식별자로 구성되며, I/G 및 U/L 제어 비트로 전송 유형과 관리 주체를 구분한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **조직 고유 식별자(Organizationally Unique Identifier, OUI)**: IEEE 표준 협회에서 제조사(하드웨어 벤더)에 할당하는 상위 24비트 고유 코드.
- **인터페이스 식별자(Network Interface Controller Specific)**: 제조사가 각 NIC 제품마다 중복되지 않도록 부여하는 하위 24비트 일련번호.

</details>

```text
[ 48비트 MAC 주소 비트 구조 ]

┌───────────────────────────────────────┬───────────────────────────────────────┐
│        상위 24비트 (OUI, 제조사 식별)   │      하위 24비트 (NIC 고유 일련번호)   │
├───────────┬───────────┬───────────────┼───────────┬───────────┬───────────────┤
│ 1st Octet │ 2nd Octet │   3rd Octet   │ 4th Octet │ 5th Octet │   6th Octet   │
└─────┬─────┴───────────┴───────────────┴───────────┴───────────┴───────────────┘
      │
      └─▶ [ b7 | b6 | b5 | b4 | b3 | b2 | U/L | I/G ]
                                           │     │
                                           │     └─▶ 0: Unicast, 1: Multicast/Broadcast
                                           └───────▶ 0: Universal(UAA), 1: Local(LAA)
```

선의 의미: 상위 24비트 OUI 내 1옥텟의 최하위 2개 비트가 주소 제어 속성(U/L, I/G)을 규정

| 구성요소 | 비트 범위 | 책임 |
|:---|:---|:---|
| **조직 고유 식별자 (OUI)** | 상위 24비트 (1~3 옥텟) | IEEE가 하드웨어 제조사에 공식 부여한 벤더 식별 코드 |
| **I/G 비트 (개별/그룹)** | 1옥텟 0번 비트 (LSB) | 0: 단일 수신자(Unicast), 1: 다중/전체 수신자(Multicast/Broadcast) 판정 |
| **U/L 비트 (전역/로컬)** | 1옥텟 1번 비트 | 0: 전역 관리 주소(UAA), 1: 로컬 관리/가상화 주소(LAA) 판정 |
| **인터페이스 식별자** | 하위 24비트 (4~6 옥텟) | 제조사가 개별 네트워크 카드마다 부여하는 고유 일련번호 |

#### 한줄 요약
- 상위 24비트 제조사 코드(OUI)와 하위 24비트 장치 일련번호로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **MAC 주소 학습(Source MAC Learning)**: L2 스위치가 수신 프레임의 출발지 MAC 주소와 인입 포트 번호를 MAC 테이블(CAM 테이블)에 동적 기록하는 과정.
- **플러딩(Flooding)**: 수신 프레임의 목적지 MAC 주소가 MAC 테이블에 존재하지 않을 때, 인입 포트를 제외한 모든 동일 VLAN 포트로 프레임을 복제 전송하는 동작.

</details>

```text
1. 이더넷 프레임 스위치 포트 인입
            │
            ▼
2. 출발지 MAC 주소 학습: [출발지 MAC ➔ 인입 포트] 매핑 정보를 CAM 테이블에 기록
            │
            ▼
3. 목적지 MAC 주소 조회: CAM 테이블에서 목적지 포트 검색
            │
            ├─ [테이블에 존재 (Known Unicast)] ──▶ 4a. 해당 포트로 단일 포워딩 (Filtering/Forwarding)
            └─ [테이블에 없음 (Unknown Unicast)] ─▶ 4b. 수신 포트 제외 전체 포트 플러딩 (Flooding)
```

**동작 원리**

1. **프레임 수신**: 스위치 물리 포트에 이더넷 프레임 인입
2. **동적 학습**: 프레임 헤더의 출발지 MAC 주소를 확인하여 해당 포트 번호와 함께 CAM 테이블에 에이징 타이머와 함께 등록
3. **목적지 검색**: 헤더의 목적지 MAC 주소를 CAM 테이블에서 조회
4. **선별 전달**: 목적지 주소가 테이블에 존재하면 해당 대상 포트로만 단일 프레임 전송(Forwarding)
5. **미식별 처리**: 목적지 주소가 없거나 브로드캐스트 주소(`FF:FF:FF:FF:FF:FF`)인 경우 동일 브로드캐스트 도메인 내 전체 포트로 플러딩 수행

#### 한줄 요약
- 출발지 MAC 주소를 CAM 테이블에 학습하고 목적지 MAC 주소 조회 결과에 따라 포워딩 또는 플러딩한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전역 관리 주소(Universally Administered Address, UAA)**: 제조사 출하시 ROM/EEPROM에 고정 기록된 전 세계 유일 주소.
- **로컬 관리 주소(Locally Administered Address, LAA)**: 가상 머신(VM), 컨테이너 또는 네트워크 관리자가 소프트웨어적으로 변경 및 재할당한 주소.

</details>

| 비교 항목 | 전역 관리 주소 (UAA) | 로컬 관리 주소 (LAA) |
|:---|:---|:---|
| **할당 주체** | IEEE 등록 하드웨어 제조사 | 시스템 관리자, 하이퍼바이저, 가상 스위치 |
| **U/L 비트 값** | **0 (Universal)** | **1 (Local)** |
| **적용 영역** | 물리적 NIC, 스위치 하드웨어 포트, 라우터 인터페이스 | VMware/KVM 가상 머신, 클라우드 컨테이너, 임시 가상 어댑터 |
| **장단점** | 전 세계적 유일성 보장 / MAC 기반 위치 추적 노출 | 주소 할당의 유연성 확보 / 로컬 세그먼트 내 중복 충돌 위험 |

#### 한줄 요약
- 하드웨어 고정 주소인 UAA와 소프트웨어 동적 할당 주소인 LAA로 구분된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MAC 스푸핑(MAC Spoofing)**: 공격자가 자신의 MAC 주소를 인가된 호스트의 MAC 주소로 변조하여 L2 스위치의 트래픽을 가로채거나 비인가 통신을 시도하는 공격.
- **포트 보안(Port Security)**: 스위치 포트별로 학습 가능한 MAC 주소의 최대 개수를 제한하거나 특정 고정 MAC만 허용하는 L2 방어 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공격자의 인가 호스트 **MAC 스푸핑** 및 중간자(MITM) 공격 | 스위치 수준 **포트 보안(Port Security)** 및 동적 ARP 검사(DAI) 적용 | 비인가 MAC 프레임 드롭 및 포트 자동 차단(Error-Disabled) |
| 대량의 위조 MAC 프레임 유입으로 스위치 CAM 테이블 오버플로우 | 포트별 **최대 MAC 학습 수 제한(Sticky MAC)** 설정 | CAM 테이블 고갈 방지 및 스위치의 허브화(플러딩 마비) 예방 |
| L2 주소 위조에 따른 네트워크 접근 제어 우회 | **IEEE 802.1X 기반 EAP 포트 기반 인증** 체계 도입 | 물리 주소 신뢰 한계 극복 및 사용자/인증서 기반 접근 통제 |

#### 한줄 요약
- 포트 보안, Sticky MAC 설정 및 IEEE 802.1X 인증을 적용하여 L2 주소 위조 공격을 방어한다.

## Ⅶ. 결론

- L2 데이터링크 계층의 주소 위조 취약성을 보완하기 위해 스위치 레벨의 **Port Security(Sticky MAC)** 설정을 기본 적용하고, 엔드포인트 무단 연결 방지를 위해 **IEEE 802.1X** 및 DAI(Dynamic ARP Inspection) 보안 체계를 결합하여 안전한 로컬 네트워크 인프라를 구축

#### 한줄 요약
- MAC 주소 체계의 구조적 특성을 기반으로 스위치 보안 기능과 포트 기반 인증을 연계한다.
