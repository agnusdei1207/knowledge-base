## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **네트워크 자동화 (Network Automation)**: 장비마다 CLI(검은 화면) 띄워놓고 밤새 타이핑하던 수작업 반복를 끊고, 파이썬 코드나 Ansible로 전국의 라우터 설정을 원클릭으로 쫙 깔아버리는 자동화 마법이다.
- **진실의 원천 (SoT, Source of Truth)**: "우리 회사 네트워크 세팅의 진짜 정답은 이거다!" 하고 모아놓은 단일 기준서다. 장비 세팅이 이거랑 다르면 전부 가짜(오류)로 간주한다.

</details>

- 정의: **네트워크 자동화** 기반 엑셀에 적어놓던 설정값(SoT)을 파이썬 코드(IaC)로 변환해서, 사람의 수동 개입 없이 수백 대 장비의 세팅을 검증, 배포, 롤백하는 프로그래밍 기반 자율 운영 체계다.
- 배경: 100대 장비에 똑같은 방화벽 룰 넣다가 한 글자 오타 나서 전국 망이 뻗는 대규모 네트워크 장애(휴먼 에러)를 막고, **클라우드 속도에 맞춰 인프라 세팅도 5분 만에 끝내려고 전면 도입됐다.** #### 한줄 요약

- 스위치마다 로그인해서 콘솔 치던 아날로그 짓을 버리고, 코딩 한 줄로 수백 대를 조종하는 네트워크 혁명이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **설정 드리프트 (Configuration Drift)**: 관리자가 새벽에 몰래 장비 세팅(CLI) 건드려놔서, 정답지(SoT)랑 실제 장비 세팅이 틀어지고 짬뽕이 된 대환장 상태다.
- **멱등성 (Idempotency)**: 코드를 1번 실행하든 100번 실행하든, 이미 똑같이 세팅돼 있으면 건드리지 않고 "바꿀 게 없다"라며 항상 동일한 결과(안전)를 보장하는 성질이다.

</details>

- **설정 드리프트 방어**: 새벽에 누가 몰래 스위치 세팅 건드려도, 자동화 봇이 귀신같이 찾아내서 정답지(SoT)대로 강제 복구(롤백)시켜 버린다.
- **코드 배포 전 검증 (CI 파이프라인)**: 명령어를 날리기 전에 가상 환경에서 먼저 돌려보고(Syntax 체크), 장비가 뻗을 거 같으면 배포 자체를 블락해버린다.
- **멱등성 보장**: 배포 스크립트를 실수로 두 번 눌러도 장비가 꼬이지 않고, "어? 아까 바꿨네? 패스~" 하고 넘어가서 운영자의 멘붕을 막아준다.

#### 한줄 요약

- 멱등성으로 두 번 쏴도 안 발생하고, 설정 드리프트 잡아서 맘대로 세팅 바꾼 놈 색출해 내는 게 핵심 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NETCONF / RESTCONF**: "시스코 다르고 주니퍼 다르네 빡치게" 하던 명령어를 통일하려고 만든, XML/JSON 기반의 글로벌 장비 제어 표준 언어(API)다.
- **Ansible (앤서블)**: 장비에 에이전트를 깔 필요 없이, SSH 하나만 뚫려 있으면 수백 대 장비에 들어가서 세팅을 집중 적용하고 나오는 수작업 반복 십장(자동화 툴)이다.

</details>

```text
[ 네트워크 자동화 직관적 비교 구조 ]

[ 진실의 원천 (SoT) / Git ] ── (우리가 원하는 정답 세팅값 저장소)
      │
      ▼
[ Ansible (수작업 반복 십장) ] ── (정답지 들고 장비들 줘팰 준비함)
      │
  (NETCONF / RESTCONF 표준어 사용)
      │
      ▼
[ 전국 이종 장비들 (Cisco, Juniper 등) ] ── (표준어로 맞으면서 세팅 쫙 바뀜)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **진실의 원천 (SoT)** | "이게 우리 망 정답지다" 하고 **목표 세팅값을 꽉 쥐고 있는 절대 기준** | Source |
| **Git / CI/CD** | 세팅 코드 짠 거 백업해 두고, **오타 난 거 없나 빡세게 자동 검사하는 놈** | Pipeline |
| **Ansible (앤서블)** | 정답지 들고 전국 장비에 접속해서 **강력히 세팅값 박아넣는 행동 대장** | Tool |
| **NETCONF / RESTCONF**| 장비 벤더 상관없이 찰떡같이 알아듣게 내리는 **표준어 명령 (API)** | Protocol |
| **YANG (데이터 모델)** | 장비 설정 항목들을 이쁘게 정리해 놓은 **데이터 표준 양식 (스키마)** | Data Model |

#### 한줄 요약

- 정답지(SoT)를 Git에 올리면 $\to$ 앤서블이 들고 뛰어가서 $\to$ NETCONF/RESTCONF 표준어로 스위치 대가리에 쑤셔 넣는 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **후보 설정 (Candidate Config)**: 장비에 룰을 바로 박아버리면 뻗을 수 있으니까, "일단 이거 먹여보고 문제없으면 확정해라" 하고 임시로 저장해 두는 테스트 폴더다.
- **롤백 (Rollback)**: 룰 먹였는데 장비가 먹통 돼서 핑이 안 나가면, 알아서 "아 시바 꿈" 하고 예전 세팅으로 되돌아오는 생명줄이다.

</details>

```text
[ 자동화 멱살 배포 및 롤백 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [사전 검증 (CI 린트 검사)]│
│ (시스템: 오타나 정책 충돌 나나 시뮬레이션 돌림)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [Ansible 배포 파이프라인] │
│ (십장: 오케이 통과. 장비들한테 표준어 날린다)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [후보 설정(Candidate) 적용]
│ (장비: 일단 임시 폴더에 세팅값 먹여보겠음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [텔레메트리 검증 (핑 테스트)]
│ (시스템: 세팅 먹이고 통신 잘 나가나 관측함!)
└──────────────┬───────────────┘
               ▼ (핑 끊기면)
┌──────────────────────────────┐
│ 5. [실패 시 자동 롤백 (복구)]│
│ (장비: 어? 통신 뻗었다! 바로 이전 세팅으로 롤백!)
└──────────────────────────────┘
```

### 동작 원리

1. 사전 검증: 개발자가 코드를 푸시하면 CI가 YANG 스키마 문법에 맞는지 선제 검사함.
2. 배포 시작: 앤서블이 통과된 코드를 들고 NETCONF/RESTCONF 통신을 쏴줌.
3. 후보 설정 적용: 장비가 Running(실가동) 설정 건드리기 전에 Candidate(후보)에 먼저 적용해 봄.
4. 실제 상태 검증: 확정(Commit) 후 텔레메트리로 라우팅이랑 핑이 진짜로 도는지 감시함.
5. 실패 시 롤백: 핑이 안 돌고 타임아웃 나면 Confirmed Commit 롤백 기능 발동해서 옛날 세팅으로 돌아옴.

#### 한줄 요약

- 오타 검사 $\to$ 장비에 쏴줌 $\to$ 후보 테스트 $\to$ 핑 확인 $\to$ 뻗으면 바로 롤백하는 개안전한 5단계 배포다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CLI 파싱 (기존 방식)**: 장비에서 출력되는 `show run` 문자열을 정규식으로 꾸역꾸역 잘라서 읽는 쌩수작업 반복다. 펌웨어 바뀌어서 띄어쓰기 하나 달라지면 스크립트 다 터진다.

</details>

| 구분 | **NETCONF (고신뢰 트랜잭션)** | **RESTCONF (웹 연동)** | **CLI 파싱 (아날로그 수작업 반복)** |
|:---|:---|:---|:---|
| 핵심 특징 | 결제 취소(롤백) 확실한 **안전 계좌이체** | 가볍게 연동하기 좋은 **간편 결제** | 영수증 글씨 하나하나 잘라 읽는 **수기 장부** |
| 통신 방식 (페이로드)| SSH 위에서 **XML 문서** 기반 무겁게 통신함 | HTTP(웹) 위에서 **JSON** 기반 가볍게 씀 | SSH(Putty) 들어가서 **문자열(Text)** 긁어옴 |
| 롤백 (안전장치) | 임시 저장소(Candidate) 지원. **실패 시 100% 롤백됨** | HTTP라 부분 적용되다 뻗을 수 있음 **(취약)** | 실패하면 에러 띄우고 멈춤 **(장비 망가진 채 방치)** |
| 장점 | 원자성(Atomicity) 보장으로 **절대 안 뻗음** | 프론트엔드 웹 대시보드 만들 때 **개편함** | API 지원 안 하는 **10년 된 구형 장비도 제어 가능** |
| 주요 용도 | 절대 뻗으면 안 되는 **백본망 코어 라우터 제어** | 웹 포털에서 원클릭으로 조작하는 **SDN 제어** | 레거시(썩다리) 장비 어쩔 수 없이 관리할 때 |

#### 한줄 요약

- 생명줄 롤백이 빵빵한 NETCONF는 뼈대 백본망에 쓰고, 가볍게 웹이랑 연동할 땐 RESTCONF, 썩다리 장비엔 CLI 파싱 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카나리 배포 (Canary)**: 100대에 한 번에 코드 쐈다가 다 같이 뻗는 걸 막으려고, 1대에 먼저 쏴보고(카나리아 새) 멀쩡하면 나머지 99대에 쏘는 개쫄보(안전 제일) 배포 전략이다.
- **텔레메트리 (Telemetry)**: SNMP처럼 5분마다 물어보는 게 아니라, 장비가 스스로 "CPU 튄다!", "패킷 드롭된다!" 하고 실시간으로 이벤트를 스트리밍 쏴주는 거다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 밤새 짠 스크립트 쐈더니 **장비 100대가 동시 셧다운됨** | 코드 하나 잘못 짰는데 전 장비에 동시 배포해서 폭망함 | 한 대 먼저 쏴보고 멀쩡한지 확인하는 **카나리(Canary) 단계별 배포 적용** | 서비스 장애 터져도 피해 규모(Blast Radius) 최소화 |
| 펌웨어 업데이트 했더니 **자동화 스크립트가 싹 다 뻗음** | CLI 출력 화면(띄어쓰기 등)이 바뀌어서 구형 파싱 정규식이 깨짐 | 무식한 문자열 파싱 버리고 **표준 구조화 데이터(YANG/NETCONF)로 갈아탐** | 장비 OS가 바뀌어도 스크립트 안 깨지고 튼튼함 |
| 룰 날렸는데 핑은 안 나가고 **조용히 라우팅 뻗어버림** | 세팅(Config)은 먹혔는데 실제 라우팅 도달성(Reachability)이 깨진 거임 | **텔레메트리** 기반 핑 도달하는지 실시간 감시하고, 안 나가면 **타임아웃 롤백** 땡김 | 조용히 뻗는 은밀한 장애(Silent Drop) 조기 진압 |

#### 한줄 요약

- 한 번에 다 쏘지 말고 카나리로 한 대씩 간 보면서 쏘고, 구형 문자열 파싱 버리고 NETCONF로 갈아타야 밤에 잠을 편히 잔다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 장비 제조사마다 파편화된 CLI 수동 설정과 휴먼 에러를 박살 내기 위해, **진실의 원천(SoT)** 기반으로 YANG/NETCONF 표준을 엮어 인프라를 지휘하는 네트워크 자동화 기조 확립함

#### 한줄 요약

- 네트워크 자동화(IaC)는 라우터 외부 캡슐화 래퍼만 만지던 아날로그 운영을 박살 내고, 깃헙(Git) 코드로 전 세계 인프라를 지휘하는 마법이다.
