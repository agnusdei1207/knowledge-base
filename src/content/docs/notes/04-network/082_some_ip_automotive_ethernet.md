## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터넷 프로토콜 기반 확장형 서비스 지향 미들웨어(Scalable service-Oriented MiddlewarE over Internet Protocol, SOME/IP)**: 차량 IP망에서 ECU 기능을 서비스로 발견하고 호출•구독하는 AUTOSAR 서비스 지향 미들웨어 규약이다.
- **자동차 개방형 시스템 아키텍처(Automotive Open System Architecture, AUTOSAR)**: 차량 소프트웨어 아키텍처 표준이다.
- **전자제어장치(Electronic Control Unit, ECU)**: 차량 기능을 제어하는 장치이다.

</details>

- 정의/개념: **SOME/IP**는 **AUTOSAR** 기반 차량 IP망에서 **ECU** 기능을 서비스로 호출•구독하는 미들웨어 규약이다.
- 배경/필요성: ECU 주소를 고정한 호출은 기능 재배치와 버전 변경에 대응하기 어렵다.

#### 한줄 요약

- 차량 ECU의 주소를 직접 알지 않아도 필요한 기능과 버전으로 제공자를 찾아 호출할 수 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **서비스 계약(Service Contract)**: 서비스 식별자(Identifier, ID)•인터페이스 버전•자료형으로 소비자와 제공자의 호출 호환성을 정한 규격이다.
- **SOME/IP 서비스 탐색(Scalable service-Oriented MiddlewarE over Internet Protocol Service Discovery, SOME/IP-SD)**: 서비스 제공 위치•버전•TTL을 광고•탐색하고 이벤트 구독을 관리하는 규약이다.
- **생존 시간(Time to Live, TTL)**: 서비스 광고와 구독 상태가 유효한 기간이다.

</details>

- **서비스 계약**으로 ID•버전•자료형이 맞는 인터페이스를 선택한다.
- 요청•응답•무응답•이벤트 통신 방식을 제공한다.
- **SOME/IP-SD**는 제공자 위치•버전과 **TTL**을 동적으로 발견•관리한다.

#### 한줄 요약

- 기능 제공 ECU가 바뀌어도 다시 찾을 수 있지만 인터페이스 버전을 확인해야 호환되지 않는 서비스 연결을 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **서비스 소비자•제공자**: 메서드 호출•이벤트 구독을 맡는 소비자와 기능 실행•이벤트 발행을 맡는 제공자이다.
- **종단 간 보호(End-to-End Protection, E2E 보호)**: 순서 번호와 검사값으로 서비스 메시지의 손상•반복•누락을 검출하는 방식이다.

</details>

- **서비스 소비자•제공자**는 호출•구독과 실행•발행 책임을 나누고 **E2E 보호**로 메시지 손상•반복•누락을 검출한다.

```text
SOME/IP
├─ 서비스 소비자
├─ 양단 SOME/IP-SD
├─ 서비스 제공자
├─ 서비스 인터페이스
└─ E2E 보호
```

선의 의미: 서비스 소비자와 제공자는 SOME/IP-SD의 위치•버전•TTL 관계이고, 양 종단은 같은 서비스 인터페이스 계약과 메시지 손상•반복•누락을 검출하는 E2E 보호 관계를 공유한다.

| 구성요소 | 책임 |
|:---|:---|
| 서비스 소비자 | 메서드 호출•이벤트 구독 |
| 양단 SOME/IP-SD | 제공 위치•버전•TTL 관리 |
| 서비스 제공자 | 메서드 실행•이벤트 발행 |
| 서비스 인터페이스 | ID•버전•자료형 계약 정의 |
| E2E 보호 | 손상•반복•누락 메시지 검출 |

#### 한줄 요약

- 소비자는 SOME/IP-SD에서 제공자의 위치와 버전을 받고 같은 인터페이스 계약으로 기능을 호출하거나 이벤트를 구독한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **서비스 제공•탐색(OfferService/FindService)**: 제공자가 서비스 ID•버전•종단점•TTL을 광고하고 소비자가 필요한 조건으로 탐색하는 절차이다.
- **이벤트 그룹**: 소비자가 관련 상태 이벤트를 하나의 단위로 묶어 구독하도록 정의한 집합이다.
- **OfferService 광고**: 제공자가 서비스 ID•버전•종단점•생존 시간을 공지하는 단계이다.
- **FindService 탐색**: 소비자가 요구 ID•버전에 맞는 제공자를 조회하는 단계이다.
- **이벤트 그룹 구독**: 관련 상태 이벤트 묶음과 구독 생존 시간을 등록하는 단계이다.
- **서비스 메시지 교환**: 메서드 결과•이벤트•종단 간 보호 상태를 양단에서 전달하는 단계이다.
- **OfferService 갱신**: 광고 만료 전에 제공 상태를 갱신하고 실패하면 재탐색하게 하는 단계이다.

</details>

```text
1. OfferService 광고
      │
      ▼
2. FindService 탐색
      │
      ▼
제공 종단점•버전 확인
      ├─ 비호환: 다른 제공자 탐색
      └─ 호환
          │
          ▼
3. 이벤트 그룹 구독
          │
          ▼
4. 서비스 메시지 교환
          │
          ▼
5. OfferService 갱신
          ├─ TTL 갱신 성공: 서비스 지속
          └─ TTL 만료: 2단계부터 재탐색
```

### 동작 원리

1. **OfferService 광고**: **OfferService 광고** 단계에서 **서비스 제공•탐색** 규약으로 ID•버전•종단점•TTL을 공지한다.
2. **FindService 탐색**: **FindService 탐색** 단계에서 요구 ID•버전의 제공자를 조회한다.
3. **이벤트 그룹 구독**: **이벤트 그룹 구독** 단계에서 **이벤트 그룹**과 TTL을 등록한다.
4. **서비스 메시지 교환**: **서비스 메시지 교환** 단계에서 메서드 결과•이벤트•E2E 상태를 전달한다.
5. **OfferService 갱신**: **OfferService 갱신** 단계에서 만료 전 광고를 갱신하고 실패하면 재탐색한다.

#### 한줄 요약

- 제공자가 기능과 위치를 알리면 소비자가 호환 버전을 선택하고 TTL이 끝나기 전에 광고와 구독을 갱신한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **요청•응답•무응답 요청**: 결과가 필요하면 응답을 받고 지연을 우선하면 처리 결과를 기다리지 않는 호출 방식이다.
- **이벤트 통지**: 제공자가 상태 변화를 구독한 여러 소비자에게 배포하는 통신 방식이다.

</details>

| SOME/IP 통신 방식 | 요청•응답 | 무응답 요청 | 이벤트 통지 |
|:---|:---|:---|:---|
| 적용 기준 | **요청•응답•무응답 요청** 중 결과가 필요한 호출 | 지연 우선 단방향 호출 | **이벤트 통지**는 상태 변화의 다중 배포 |
| 핵심 특징 | 요청별 응답•오류 반환 | Fire & Forget 처리 | 구독자 대상 Notification |
| 한계 | 응답 지연•세션 관리 | 처리 성공 확인 곤란 | 구독 폭증•상태 노후화 |

#### 한줄 요약

- 답이 필요하면 요청•응답, 결과를 기다리지 않으면 무응답 요청, 상태 변화를 배포하면 이벤트 통지를 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **계약 테스트(Contract Test)**: 서비스 소비자와 제공자의 ID•버전•자료형•직렬화 호환성을 검증하는 시험이다.
- **생존 시간 튜닝(Time to Live Tuning, TTL 튜닝)**: 서비스 광고와 구독 상태의 유효 시간을 탐색 부하와 장애 재발견 시간에 맞춰 조정하는 작업이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: 다항식 나머지로 메시지 오류를 검출하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 배포 간 버전 불일치 | 호환 규칙과 **계약 테스트** 적용 | 오호출과 직렬화 오류 방지 |
| SD 광고의 멀티캐스트 폭증 | **TTL 튜닝** | 탐색 부하와 재연결 시간 균형 |
| 제어 데이터의 누락•반복 | 카운터•**CRC** 기반 **E2E 보호** | 오류 검출과 안전 반응 연결 |

#### 한줄 요약

- 계기판은 SOME/IP-SD로 속도 서비스의 호환 버전을 찾고 주행 속도 이벤트 그룹을 구독한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **통신 방식 선택(Communication Pattern Selection)**: 결과 필요 여부•지연 허용치•구독자 수에 따라 요청•응답•무응답•이벤트를 결정하는 과정이다.

</details>

- **통신 방식 선택**에서 결과가 필요한 호출과 지연 우선 호출은 **요청•응답•무응답 요청**, 다중 배포는 **이벤트 통지**가 핵심이다.

#### 한줄 요약

- 서비스 계약과 TTL을 먼저 맞추고 결과 필요 여부와 구독 규모에 따라 메서드 또는 이벤트 방식을 선택한다.
