## 미리 알고가기

- **전송 제어 프로토콜(Transmission Control Protocol, TCP)**: 순서·확인 응답·재전송·흐름 제어를 제공하는 연결형 바이트 스트림 프로토콜
- **사용자 데이터그램 프로토콜(User Datagram Protocol, UDP)**: 연결 설정·재전송 없이 독립된 데이터그램을 전달하는 프로토콜
- **스트림 제어 전송 프로토콜(Stream Control Transmission Protocol, SCTP)**: 메시지 경계·다중 스트림·다중 경로 장애 전환을 지원하는 신뢰성 전송 프로토콜
- **확인 응답(Acknowledgment, ACK)**: 수신한 데이터 범위나 다음에 받을 순서 번호를 송신자에게 알리는 응답
- **바이트 스트림(Byte Stream)**: 응용 메시지 경계를 보존하지 않고 데이터를 연속된 바이트 순서로 전달하는 모델
- **데이터그램(Datagram)**: 각 전송 단위가 독립된 메시지 경계와 목적지 정보를 갖는 모델
- **연관(Association)**: SCTP에서 여러 주소·스트림을 포함해 두 종단 사이의 통신 상태를 나타내는 연결
- **멀티호밍(Multi-Homing)**: 한 SCTP 연관의 종단이 여러 인터넷 프로토콜 주소·경로를 등록해 주 경로 장애 때 대체 경로로 전환하는 기능
- **멀티스트리밍(Multi-Streaming)**: 한 SCTP 연관 안에서 순서 번호 공간이 다른 여러 스트림을 독립적으로 전송하는 기능
- **선두 차단(Head-of-Line Blocking)**: 앞 데이터의 손실·지연 때문에 뒤의 정상 데이터까지 응용 전달을 기다리는 현상



## Ⅰ. 개요

- **정의/개념**: 전송 단위·신뢰·경로 기능이 다른 프로토콜군
- **배경/필요성**: 메시지 경계·손실 복구·지연·경로 요구별 선택

### 쉽게 이해하기 (학습용)

- 빠른 도착, 빠짐없는 전달, 메시지 구분, 장애 경로 전환 중 무엇이 필요한지에 따라 운송 방식을 정한다

## Ⅱ. 특징

- TCP 재전송·순서 제어가 신뢰성 바이트 흐름을 제공한다.
- UDP의 최소 제어는 지연을 줄이지만 복구를 응용에 위임한다.
- SCTP 멀티스트리밍은 스트림 간 선두 차단을 분리한다.
- SCTP 멀티호밍은 주소 경로 장애를 연관 안에서 전환한다.

### 쉽게 이해하기 (학습용)

- UDP는 잃은 메시지를 스스로 다시 보내지 않으므로 필요한 서비스만 응용 규칙으로 복구한다

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| TCP 바이트 흐름 | 연결별 순서·재전송·흐름을 제어 |
| UDP 데이터그램 | 독립 메시지를 최소 제어로 전달 |
| SCTP 연관 | 메시지 스트림·다중 경로를 관리 |

> 요약: 바이트 흐름·데이터그램·연관으로 전송 상태 구분

### 쉽게 이해하기 (학습용)

- TCP·SCTP는 전송 계층이 복구하고 UDP는 필요한 복구를 응용이 직접 맡는다

## Ⅳ. 원리 및 절차 흐름도

| 작동 원리 | 설명 |
|:---|:---|
| TCP 연속 전송 | ACK·재전송·수신 윈도로 바이트 제어 |
| UDP 독립 전송 | 연결 상태 없이 데이터그램 전달 |
| SCTP 스트림 전송 | 스트림별 순서와 대체 경로 관리 |

> 요약: TCP 재전송, UDP 응용 복구, SCTP 스트림·경로 분리

### 쉽게 이해하기 (학습용)

- TCP는 빠진 바이트를 채우고 UDP는 응용에 복구를 맡기며 SCTP는 스트림과 경로를 나눠 관리한다

## Ⅴ. 종류 및 비교

| 판단 기준 | TCP | UDP | SCTP |
|:---|:---|:---|:---|
| 핵심 특징 | 신뢰성 바이트 스트림 | 비연결 데이터그램 | 신뢰성 메시지·다중 스트림 |
| 적용 기준 | 순서·손실 없는 연속 데이터 | 일부 손실보다 지연이 중요한 메시지 | 메시지 경계·경로 전환이 모두 필요 |
| 주요 위험 | 선두 차단·연결 설정 지연 | 손실·중복·순서 변경을 응용이 처리 | 중간 장비·구현 지원 제약 |

> 요약: 바이트 TCP, 독립 메시지 UDP, 다중 스트림·경로 SCTP

### 쉽게 이해하기 (학습용)

- TCP는 바이트 흐름, UDP는 독립 메시지, SCTP는 여러 스트림과 경로가 필요할 때 맞는다

## Ⅵ. 실무 사례

1. 데이터베이스 세션은 TCP로 순서·재전송 보장
2. 실시간 음성은 UDP로 늦은 데이터 재전송 생략
3. 제어 신호는 SCTP로 메시지·경로 전환 지원

### 쉽게 이해하기 (학습용)

- 데이터베이스 명령과 결과는 순서가 바뀌거나 빠지면 안 되므로 TCP가 복구를 맡는다
- 늦게 다시 온 음성 조각은 재생에 쓸 수 없으므로 UDP로 보내고 응용이 손실을 감춘다
- 제어 신호는 메시지 경계를 지키면서 한 네트워크 경로가 끊겨도 등록한 다른 경로로 전환한다

## Ⅶ. 결론

- 신뢰·지연·메시지·경로 요구로 전송 선택

### 쉽게 이해하기 (학습용)

- 빠짐없는 바이트가 필요한지 늦지 않은 메시지가 필요한지 경로 전환까지 필요한지로 선택한다
