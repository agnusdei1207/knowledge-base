## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **도메인 이름 시스템(Domain Name System, DNS)**: 계층적 트리 구조를 기반으로 호스트의 도메인 이름(FQDN)을 네트워크 계층의 IP 주소로 상호 매핑 및 변환해 주는 분산 데이터베이스 시스템.
- **자원 레코드(Resource Record, RR)**: 도메인 네임에 매핑된 IP 주소, 메일 서버, 네임서버 정보 등을 표현하는 DNS의 기본 데이터 단위(A, AAAA, CNAME, MX, NS, SOA 등).

</details>

- 정의/개념: 계층적 분산 네임스페이스를 기반으로 **자원 레코드(Resource Record)** 를 조회하여 호스트명을 IP 주소로 변환하는 글로벌 분산 데이터베이스 시스템인 **DNS**
- 배경/필요성: 중앙 집중식 `hosts.txt` 파일 관리의 확장성 한계 극복 및 호스트 증가에 따른 분산 관리와 부하 분산 요구

#### 한줄 요약
- 호스트명을 IP 주소로 변환하는 전 세계 규모의 계층적 분산 데이터베이스 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **위임(Delegation)**: 도메인 네임스페이스의 특정 서브트리 관리 권한을 하위 네임서버로 공식 위임(NS 레코드)하여 분산 관리하는 메커니즘.
- **유효 시간(Time To Live, TTL)**: DNS 응답 데이터를 로컬 캐시에 유지할 수 있는 유효 기간을 초 단위로 명시한 필드.
- **DNSSEC(DNS Security Extensions)**: 공개키 암호화 전자서명을 통해 DNS 응답 데이터의 위변조 방지 및 출처 진위성을 검증하는 보안 확장 표준(RFC 4033).

</details>

- 루트(Root), 최상위 도메인(TLD), 2차 도메인(SLD)으로 구성된 계층적 **위임(Delegation)** 아키텍처
- **유효 시간(TTL)** 기반 캐싱을 통한 DNS 질의 지연 시간 최소화 및 글로벌 트래픽 부하 분산
- 캐시 포이즈닝(Cache Poisoning) 방지를 위한 **DNSSEC** 전자서명 기반 데이터 무결성 보증

#### 한줄 요약
- 계층적 위임과 캐싱(TTL)을 기반으로 동작하며, DNSSEC을 통해 무결성을 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **재귀 리졸버(Recursive Resolver)**: 클라이언트(스텁 리졸버)의 요청을 대신하여 루트 서버부터 권한 서버까지 반복 질의를 수행하고 최종 IP를 반환하는 네임서버(로컬 DNS).
- **권한 있는 네임서버(Authoritative Name Server)**: 특정 도메인 영역(Zone)의 공식 원본 자원 레코드를 보유하고 직접적인 응답을 제공하는 최종 네임서버.

</details>

```text
[ 클라이언트 (스텁 리졸버) ]
            │
            ▼ (재귀 질의, Recursive Query)
[ 재귀 리졸버 (Local DNS Server) ]
   ├─ 1. 반복 질의 (Iterative Query) ──▶ [ 루트 네임서버 (Root Name Server) ]
   ├─ 2. TLD 위임 정보 수신 ────────▶ [ TLD 네임서버 (.com / .kr) ]
   └─ 3. 권한 질의 ─────────────────▶ [ 권한 있는 네임서버 (Authoritative Server) ]
                                                │ (최종 A 레코드 응답)
                                                ▼
                                    [ 캐시 저장 후 클라이언트에 최종 응답 ]
```

선의 의미: 클라이언트와 재귀 리졸버 간의 재귀 질의 및 재귀 리졸버와 계층별 서버 간의 반복 질의 흐름

| 구성요소 | 책임 |
|:---|:---|
| **스텁 리졸버(Stub Resolver)** | 애플리케이션의 도메인 변환 요청을 수신하여 로컬 재귀 리졸버로 전달 |
| **재귀 리졸버(Recursive Resolver)** | 클라이언트를 대신해 루트부터 권한 서버까지 반복 질의를 수행하고 캐시 유지 |
| **루트(Root) 네임서버** | 도메인 트리의 최상위 노드로서 TLD 네임서버의 NS 레코드 위치 정보 반환 |
| **TLD 네임서버** | `.com`, `.net`, `.kr` 등 최상위 도메인별 하위 권한 네임서버 위치 안내 |
| **권한 있는 네임서버** | 실제 도메인의 원본 존 파일(Zone File)을 관리하고 확정적 IP 레코드 응답 |

#### 한줄 요약
- 스텁 리졸버, 재귀 리졸버, 루트, TLD, 권한 있는 네임서버의 계층적 연동으로 주소를 변환한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **존 파일(Zone File)**: 특정 도메인 권한 영역 내에 포함된 모든 자원 레코드(SOA, NS, A, CNAME 등)가 텍스트 형식으로 정의된 원본 설정 파일.

</details>

```text
1. 클라이언트(브라우저)가 로컬 재귀 리졸버에 재귀 질의(Recursive Query) 전송
            │
            ▼ (캐시 미스 발생 시)
2. 재귀 리졸버가 루트 네임서버에 반복 질의 전송 ➔ TLD 네임서버 위치 수신
            │
            ▼
3. 재귀 리졸버가 TLD 네임서버에 반복 질의 전송 ➔ 권한 네임서버 위치 수신
            │
            ▼
4. 재귀 리졸버가 권한 네임서버에 질의 전송 ➔ 최종 A/AAAA 자원 레코드 수신
            │
            ▼
5. 재귀 리졸버가 결과를 TTL 동안 캐싱하고 클라이언트에 최종 IP 주소 반환
```

**동작 원리**

1. **질의 인입**: 클라이언트 OS가 로컬 DNS(재귀 리졸버)에 도메인 해석 요청
2. **캐시 조회**: 재귀 리졸버가 자체 캐시를 검색하고 미보유 시 외부 반복 질의 시작
3. **루트/TLD 질의**: 루트 서버로부터 해당 TLD 서버를 안내받고, TLD 서버로부터 대상 도메인의 권한 서버 NS 레코드 획득
4. **권한 응답**: 권한 있는 네임서버가 요청 도메인의 실제 IP 매핑 레코드 반환
5. **캐싱 및 반환**: 수신된 응답을 TTL 동안 메모리에 캐싱한 후 클라이언트에게 IP 전달

#### 한줄 요약
- 로컬 캐시 확인 후 루트, TLD, 권한 서버를 거치는 반복 질의로 정답을 찾아 반환한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **재귀 질의(Recursive Query)**: 요청을 받은 서버가 최종 응답을 얻을 때까지 다른 서버에 직접 질의하여 클라이언트에게 완전한 결과를 반환하는 방식.
- **반복 질의(Iterative Query)**: 요청을 받은 서버가 정답을 알지 못할 경우 자신이 알고 있는 다음 하위 네임서버의 위치(Referral)를 반환하는 방식.

</details>

| 비교 항목 | 재귀 질의 (Recursive Query) | 반복 질의 (Iterative Query) |
|:---|:---|:---|
| **질의 주체** | 클라이언트 $\rightarrow$ 재귀 리졸버 (Local DNS) | 재귀 리졸버 $\rightarrow$ 루트/TLD/권한 네임서버 |
| **응답 데이터** | 최종 정답 IP 주소 또는 실패(NXDOMAIN) | 다음 단계 네임서버의 주소 힌트(Referral) |
| **서버 부하** | 질의 완료 시까지 상태를 유지하므로 부하 높음 | 단순 참조 정보만 즉시 응답하므로 부하 낮음 |
| **캐싱 적용** | 수신된 최종 응답을 TTL 동안 캐싱 | 각 단계별 네임서버 위치 정보(NS) 캐싱 |

#### 한줄 요약
- 최종 정답을 요구하는 재귀 질의와 다음 단계 힌트를 안내하는 반복 질의로 구분된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DNS 캐시 포이즈닝(Cache Poisoning)**: DNS 트랜잭션 ID와 UDP 포트를 위조하여 재귀 리졸버의 캐시에 가짜 IP 매핑을 주입하는 공격.
- **응답률 제한(Response Rate Limiting, RRL)**: DNS 증폭 공격에 악용되는 것을 방지하기 위해 동일 출발지 IP에 대한 초당 응답 건수를 제한하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 IP 이전 시 이전 IP 캐시 잔존으로 인한 접속 불가 | 이전 수일 전 사전 **TTL 값 축소(예: 300초)** 설정 및 완료 후 정상화 | 전파 지연 최소화 및 신속한 트래픽 전환 |
| DNS 증폭 디도스(Amplification DDoS) 공격 악용 | 오픈 리졸버 차단, Recursion 제한 및 **응답률 제한(RRL)** 활성화 | 반사 증폭 트래픽 차단 및 서버 자원 보호 |
| 캐시 포이즈닝에 의한 파밍 및 피싱 사이트 유도 | **DNSSEC(전자서명 검증)** 도입 및 소스 포트 무작위화(SPR) 적용 | 위조된 DNS 응답 폐기 및 데이터 무결성 보증 |
| 존 전송(Zone Transfer) 취약점으로 인한 사내 인프라 노출 | 네임서버 간 동기화에 **TSIG(트랜잭션 서명)** 및 접근 IP 제한 적용 | 비인가 존 전송 차단 및 도메인 레코드 기밀성 유지 |

#### 한줄 요약
- 사전 TTL 축소, DNSSEC 무결성 검증, RRL 속도 제한 및 TSIG 존 보호로 안정성을 확보한다.

## Ⅶ. 결론

- 글로벌 인터넷 인프라의 핵심인 **DNS**의 안정적 운용을 위해 계층적 위임 구조와 TTL 기반 캐싱을 최적화하고, 주소 변조 공격에 대응하기 위해 **DNSSEC** 및 RRL 보안 설정을 필수로 적용하여 고가용성과 신뢰성을 동시에 보장

#### 한줄 요약
- 계층적 네임스페이스 관리와 DNSSEC 보안 확장을 통해 고가용성 도메인 변환 환경을 구현한다.
