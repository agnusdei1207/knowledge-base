## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DNS (Domain Name System)**: 호스트의 도메인 이름(FQDN)을 L3 IP 주소로 상호 변환해 주는 계층적 분산 데이터베이스 시스템.
- **Resource Record (자원 레코드, RR)**: 도메인에 매핑된 IP(A/AAAA), 별칭(CNAME), 메일서버(MX), 네임서버(NS), 권한시작(SOA) 정보 단위.

</details>

- 정의/개념: 사람이 식별하는 도메인 이름(FQDN)을 **L3 IP 주소로 상호 변환하는 계층적 분산 데이터베이스 시스템**
- 배경/필요성: 초기 인터넷의 중앙 집중식 `hosts.txt` 파일 단일 배포 방식이 호스트 수의 기하급수적 증가에 따른 전 세계 단말 파일 동기화 지연, 이름 중복 충돌 및 단일 장애점(SPOF) 병목을 유발하던 한계를 극복하기 위해, 루트(`.`), TLD(`.com`), 2차 도메인으로 이어지는 계층적 트리 구조와 도메인 관리 권한 위임(Delegation) 메커니즘, 그리고 리졸버의 TTL 기반 분산 캐싱을 결합한 DNS(Domain Name System)를 도입하여 **전 세계 수십억 개 호스트의 도메인-IP 상호 변환에 대한 무제한 확장성과 초저지연 분산 네임 해석**을 달성할 필요

#### 한줄 요약
- 루트, TLD, 권한 서버의 계층적 위임과 캐싱을 통해 전 세계 도메인 이름을 고속 변환한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Delegation (위임)**: 상위 도메인 네임서버가 특정 서브도메인의 관리 권한을 하위 권한 네임서버(NS 레코드)로 공식 이양하는 메커니즘.
- **DNSSEC (DNS Security Extensions)**: 전자서명(RRSIG)과 공개키 검증(DNSKEY)을 통해 DNS 응답의 위변조를 방지하는 보안 확장 표준 (RFC 4033).

</details>

- 루트(`.`), TLD(`.com`), 2차 도메인으로 이어지는 **계층적 네임스페이스 및 위임(Delegation)**
- 질의 지연시간을 단축하고 글로벌 트래픽 부하를 분산하는 **TTL(Time-To-Live) 기반 캐싱**
- 캐시 포이즈닝(Cache Poisoning) 위변조를 원천 차단하는 **DNSSEC 전자서명 무결성 검증**

#### 한줄 요약
- 계층적 위임 구조, TTL 기반 캐싱, DNSSEC 전자서명을 통해 고속성과 무결성을 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DNS 4대 서버 계층**: Stub Resolver(클라이언트 라이브러리), Recursive Resolver(로컬 DNS), Root/TLD Server, Authoritative Server(최종 권한 서버).

</details>

```text
[DNS 질의 체계]
|-- 스텁 리졸버
|-- 재귀 리졸버
`-- 권한 계층
    |-- 루트 네임서버
    |-- TLD 네임서버
    `-- 권한 있는 네임서버
```

선의 의미: 계층 및 클라이언트의 재귀 질의를 수신한 로컬 리졸버가 루트, TLD, 권한 서버에 반복 질의를 수행하여 IP를 찾는 구조

| 구성요소 | 책임 |
|:---|:---|
| 스텁 리졸버 | 응용의 질의를 재귀 리졸버에 전달 |
| 재귀 리졸버 | 반복 질의 수행과 응답 캐싱 |
| 루트 네임서버 | TLD 네임서버 참조 제공 |
| TLD 네임서버 | 하위 권한 서버 참조 제공 |
| 권한 있는 네임서버 | 원본 존의 **자원 레코드** 응답 |

#### 한줄 요약
- 재귀 리졸버가 스텁과 권한 계층 사이에 끼어들어 캐시된 사본으로 응답함으로써, 질의마다 루트·TLD·권한 서버를 차례로 밟아야 하던 왕복을 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **도메인 질의 5단계**: 클라이언트 재귀 질의 $\to$ 리졸버 캐시 미스 $\to$ 루트/TLD 반복 질의 $\to$ 권한 서버 A 레코드 수신 $\to$ 캐싱 및 최종 반환.

</details>

```text
클라이언트 브라우저 도메인(`example.com`) 조회 착수
        │
   1. [재귀 질의 (Recursive)] 브라우저가 로컬 재귀 리졸버에 도메인 해석 요청
        │
   2. [캐시 확인 및 루트 질의] 캐시 미스 시 재귀 리졸버가 Root 서버에 반복 질의 (TLD 안내 수신)
        │
   3. [TLD 서버 반복 질의] `.com` TLD 서버에 질의하여 `example.com` 권한 네임서버 NS 획득
        │
   4. [권한 서버 최종 질의] `example.com` 권한 서버에 질의하여 최종 A 레코드(`93.184.216.34`) 수신
        │
   5. [캐싱 및 클라이언트 응답] 수신된 IP를 TTL(3600초) 동안 캐시에 저장하고 클라이언트에 최종 반환
```

- 1. 재귀 질의: 스텁이 리졸버에 최종 답 요청
- 2. 캐시 확인 및 루트 질의: 캐시 미스 시 TLD 참조 획득
- 3. TLD 서버 반복 질의: 권한 서버 참조 획득
- 4. 권한 서버 최종 질의: A·AAAA 레코드 획득
- 5. 캐싱 및 클라이언트 응답: TTL 저장 후 결과 반환

#### 한줄 요약
- 캐시 적중이면 왕복 1회로 끝나지만 미스면 루트·TLD·권한 서버 세 번의 반복 질의를 리졸버가 대신 치르므로, TTL은 갱신 지연과 상위 서버 부하 사이의 교환 비율이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Recursive Query (재귀 질의)** vs **Iterative Query (반복 질의)**: 최종 정답을 찾아줄 것을 위임하는 질의(재귀)와 다음 단계 네임서버 힌트만 제공하는 질의(반복).

</details>

| 비교 항목 | 재귀 질의 (Recursive Query) | 반복 질의 (Iterative Query) |
|:---|:---|:---|
| 질의 주체 | 스텁 리졸버 | 재귀 리졸버 |
| 질의 대상 | 재귀 리졸버 | 루트·TLD·권한 서버 |
| 응답 내용 | 최종 답 또는 NXDOMAIN | 다음 서버 참조 정보 |
| 캐싱 대상 | 최종 자원 레코드 | NS와 글루 레코드 |

#### 한줄 요약
- 재귀 질의는 해석 부담을 리졸버에 떠넘겨 단말을 가볍게 하고, 반복 질의는 권한 서버가 상태 없이 참조만 돌려주게 해 전 세계 부하를 계층으로 흩어 놓는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DNS Cache Poisoning (캐시 포이즈닝)**: 공격자가 UDP 트랜잭션 ID와 소스 포트를 위조하여 재귀 리졸버의 캐시에 가짜 IP 매핑을 주입하는 파밍 공격.
- **RRL (Response Rate Limiting)**: DNS 서버가 증폭 디도스(Amplification DDoS) 공격의 반사체로 악용되는 것을 방지하기 위해 동일 IP에 대한 초당 응답 건수를 제한하는 기법.
- **TSIG (Transaction Signature)**: 네임서버 간에 미리 공유한 비밀키로 DNS 메시지에 HMAC을 덧붙여, 존 전송(AXFR/IXFR)과 동적 갱신 요청의 발신자와 무결성을 검증하는 트랜잭션 인증 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 IP 변경 시 전 세계 캐시 잔존으로 인한 접속 장애 | 작업 수일 전 사전 TTL 단축(예: 300초) 및 완료 후 원복 | DNS 전파 지연 최소화 및 신속한 롤백 |
| 공격자의 **캐시 포이즈닝**으로 인한 피싱/파밍 사이트 유도 | **DNSSEC** 서명(RRSIG) 검증 및 소스 포트 무작위화 | 위조 DNS 응답 드롭 및 데이터 무결성 보증 |
| 오픈 리졸버를 악용한 DNS 반사 증폭 디도스 공격 | 외부 재귀 질의 차단(Closed Resolver) 및 **RRL** 활성화 | 반사 증폭 트래픽 차단 및 서버 보호 |
| 존 전송(AXFR) 취약점으로 인한 사내 전체 서버 토폴로지 유출 | 존 전송에 **TSIG** 서명 및 허용 IP 제한 | 비인가 존 전송 차단 및 정보 노출 방어 |

#### 한줄 요약
- DNS의 성능은 캐시 사본을 믿는 데서 나오고 취약점도 같은 곳에서 나오므로, 대책은 사본의 진위(DNSSEC·TSIG)와 사본의 수명(TTL)을 따로 통제하는 일이다.

## Ⅶ. 결론

- 전 세계 인터넷 서비스의 첫 관문이자 글로벌 트래픽 라우팅(GSLB) 및 Anycast 기반 CDN 분산 제어의 핵심을 담당하는 **가장 중추적인 계층적 분산 디렉터리 인프라 표준**으로 자리잡았으며, 실무 구축 및 운영 시에는 **캐시 포이즈닝 파밍 공격을 원천 차단하는 DNSSEC(RRSIG) 전자서명 체계 도입, 점검/이관 시 무중단 전환을 위한 사전 TTL 단축, 증폭 DDoS 방지를 위한 폐쇄형 리졸버(Closed Resolver) 및 RRL(Response Rate Limiting) 정책 적용, 도메인 질의 도청을 방지하는 DoH(DNS over HTTPS)/DoT 암호화 통신**을 결합하여 가용성과 보안성을 동시에 완성

#### 한줄 요약
- DNS는 계층적 위임과 반복 질의를 통해 도메인 이름을 IP로 변환하며, DNSSEC과 Anycast를 결합하여 고가용성과 보안성을 보장하는 핵심 인터넷 인프라 기술이다.
