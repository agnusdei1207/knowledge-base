## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **도메인 이름 시스템(DNS, Domain Name System)**: 사람이 외우기 쉬운 영문 주소(naver.com)를 컴퓨터가 알아먹는 숫자 IP 주소(192.168.0.1)로 번역해 주는 전 세계 규모의 인터넷 전화번호부이다.
- **자원 레코드(Resource Record, RR)**: "www는 이 IP고, 메일 서버는 저 IP다" 하고 DNS 전화번호부 안에 적어놓는 핵심 데이터 한 줄이다.

</details>

- 정의: 영문 도메인 이름과 자원 레코드를 IP 주소로 번역해 주는 글로벌 분산 **DNS**
- 배경: 컴퓨터 한 대의 hosts 파일에 수십억 개의 인터넷 주소를 다 구겨 넣고 관리하는 건 **물리적으로 불가능했기 때문**

#### 한줄 요약

- 숫자 IP를 외우기 귀찮은 인간을 위해 영문 주소를 숫자로 번역해 주는 거대한 전화번호부다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **위임(Delegation)**: 대장 서버(Root)가 다 외우지 않고, ".com 주소는 쟤한테 물어봐, .kr은 얘한테 물어봐" 하고 책임을 밑으로 떠넘기는 다단계 구조이다.
- **유효 시간(TTL, Time To Live)**: "이 번호는 300초 동안 안 바뀌니까 그동안은 또 묻지 말고 니가 기억해라" 하고 캐시(Cache)에 저장해 두는 타이머이다.
- **DNSSEC** 나쁜 놈이 보이스피싱처럼 가짜 IP를 알려주는 걸 막기 위해, 진짜 서버가 줬다는 걸 암호로 서명해서 증명하는 보안 기술이다.

</details>

- 루트(Root) 및 최상위 도메인(TLD) 네임서버 체계 중심의 계층적 **위임(Delegation)** 아키텍처.
- **유효 시간(TTL)** 튜닝을 통해 트래픽 부하 분산과 도메인 변경 사항의 전파 속도를 조율.
- 가짜 IP 납치를 막기 위해 **DNSSEC** 암호화 서명으로 응답 데이터의 출처 인증 및 무결성 보장.

#### 한줄 요약

- 책임을 쪼개서 넘기고(위임), 한 번 들은 건 외워두고(TTL), 사기 안 당하게 인증(DNSSEC)한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **재귀 리졸버(Recursive Resolver)**: 내 컴퓨터 대신 전 세계 DNS 서버를 싹 다 뒤져서 정답을 알아다 주는 동네 심부름꾼(통신사 DNS, 8.8.8.8)이다.
- **권한 있는 네임서버(Authoritative Name Server)**: 자원 레코드의 찐 원본을 들고 있어서, 카더라(캐시)가 아닌 "이게 진짜 내 IP다"라고 확정해서 대답하는 최종 서버이다.

</details>

```text
[ DNS 다단계 분산 팩트 폭행 아키텍처 ]

[ PC 브라우저 ] ───── (나 네이버 갈래!) ─────▶ [ 재귀 리졸버 ]
                                                    │ (심부름꾼)
                                                    │
                  [ 1. 루트 서버 ] ◀── (.com은 저기로 가) ─┤
                                                    │
                  [ 2. TLD 서버 ] ◀── (naver는 저기로 가) ─┤
                                                    │
                  [ 3. 권한 서버 ] ◀── (www는 이 IP야!) ──┘
```

| 구성요소 | 팩트 폭행 책임 |
|:---|:---|
| **스텁 리졸버 (OS 내장)** | PC 안에서 "주소 좀 찾아줘" 하고 재귀 리졸버한테 짬 때리는 가짜 리졸버 |
| **재귀 리졸버 (로컬 DNS)**| 내 대신 전 세계 서버를 뺑뺑이 돌면서 답을 찾아오고, 메모리에 저장(캐시)하는 놈 |
| **루트(Root) 네임서버** | 전 세계 13대뿐인 대빵. 최상위 도메인(.com, .net) 서버 위치를 알려줌 |
| **TLD (최상위) 네임서버** | `.com`이나 `.kr`을 관리하며, 진짜 도메인(naver)의 권한 서버 위치를 알려줌 |
| **권한 있는 네임서버** | 찐 원본 자원 레코드를 들고 "내 IP는 이거다"라고 확정 대답을 해주는 주소 주인 |
| **자원 레코드 (RR)** | A(IPv4), AAAA(IPv6), CNAME(별칭) 같은 진짜 IP 매핑 데이터 |

#### 한줄 요약

- 내 PC가 심부름꾼(재귀)을 시키면, 심부름꾼이 루트$\to$TLD$\to$권한 서버를 돌며 답을 캐온다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 미스(Cache Miss)**: 재귀 리졸버가 자기 머릿속(메모리)을 뒤져봤는데 해당 도메인의 IP를 모를 때, 바깥세상(루트 서버)으로 물어보러 나가야 하는 상태이다.
- **위임 경로 질의(Delegation Path Query)**: Root $\to$ TLD $\to$ 권한 서버 순으로 "형님 쟤 누군지 아심?" 하면서 계속 다음 타자를 찾아가는 뺑뺑이 절차이다.

</details>

```text
[ DNS 질의응답 십자포화 흐름 ]
┌──────────────────────────────┐
│ 1. PC가 재귀 리졸버에 질문   │
│ ("naver.com 어딨음?")        │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. 리졸버 캐시 미스 (모름)   │
│ (머릿속에 없네... 찾아볼게)  │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. 위임 경로 뺑뺑이 질의     │
│ (Root -> TLD -> 권한 서버)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. 권한 서버 최종 응답       │
│ ("여기 찐 IP 받으쇼!")       │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. 캐싱 및 PC로 결과 반환    │
│ (TTL만큼 기억해 두고 PC에 줌)│
└──────────────────────────────┘
```

### 동작 원리

1. PC 질의: 브라우저가 통신사(로컬) DNS한테 도메인 IP를 물어봄.
2. 캐시 미스: 로컬 DNS가 자기 메모리를 뒤졌는데 모르면 바깥으로 나감.
3. 위임 경로 뺑뺑이: 루트, TLD, 권한 서버를 차례대로 찌르면서 힌트를 얻음.
4. 권한 응답: 찐 주인(권한 서버)이 원본 IP 레코드를 던져줌.
5. 캐싱 및 반환: 로컬 DNS가 TTL 시간만큼 기억해 두고 PC에 답을 줌.

#### 한줄 요약

- 모르면 바깥으로 나가서 뺑뺑이 돌고, 알아온 건 까먹기 전(TTL)까지 외워두고 써먹는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **재귀 질의(Recursive Query)**: "난 모르니까 니가 어떻게든 끝까지 찾아서 정답만 가져와" 하고 모든 책임을 떠넘기는 귀찮은 질문 방식이다.
- **반복 질의(Iterative Query)**: "나도 정확힌 모르는데, 저기 가면 알 수도 있음" 하고 자기 아는 선에서만 힌트(Referral)를 던지고 손절하는 방식이다.

</details>

| 비교 항목 | **재귀 질의 (끝까지 책임져!)** | **반복 질의 (저기 가서 물어봐)** |
|:---|:---|:---|
| 질의 주체 | **PC $\to$ 재귀 리졸버(로컬 DNS)** | **재귀 리졸버 $\to$ 전 세계 네임서버들** |
| 응답 형태 | **최종 정답 IP 주소** 하나만 딱 줌 | 내가 아는 **다음 서버 주소(힌트)**만 띡 던짐 |
| 서버 부하 | 뺑뺑이 돌고 기억까지 해야 해서 **부하 개쩜** | 모른다고 토스만 하니까 **부하 없음** |
| 악용 위험 | 해커가 쓰레기 쿼리 날리면 총알받이 됨 | 기능이 단순해서 공격받을 확률 낮음 |

#### 한줄 요약

- 내 PC는 뻔뻔하게 정답만 내놓으라(재귀) 하고, 로컬 DNS는 전 세계를 돌며 힌트(반복)를 수집한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DNS 증폭 공격(DNS Amplification Attack)**: 해커가 내 IP로 위장해서 DNS한테 질문을 던지면, 멍청한 DNS가 나한테 수백 배 큰 대답 쓰레기를 부어버려 터트리는 공격이다.
- **트랜잭션 서명(TSIG, Transaction Signature)**: 1차 DNS와 2차 DNS끼리 주소록(존 파일)을 복사할 때, 아무나 못 빼가게 비밀번호(HMAC 암호키)를 걸어 잠그는 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 이사 갔는데 옛날 IP가 캐시에 남아서 며칠간 접속 안 됨 | 서버 이사 가기 전에 미리 **TTL을 300초(5분)로 대폭 축소** | 이사하자마자 새 IP로 바로 접속됨 |
| 대문 열어놓은 로컬 DNS가 **증폭 DDoS 공격** 총알받이로 쓰임 | 외부 IP 질문 씹고 속도 조절하는 **RRL(응답률 제한)** 도입 | 좀비 서버로 악용되는 거 원천 차단 |
| 해커가 가짜 IP를 DNS 캐시에 밀어 넣어서 피싱 사이트로 납치 | 응답에 진짜 서버 서명을 박아넣는 **DNSSEC** 의무화 | 주소록(캐시) 위변조 보이스피싱 차단 |
| 해커가 사내 서버 전체 IP 목록(Zone File)을 통째로 털어감 | 1/2차 DNS끼리만 동기화되게 **TSIG 암호 서명** 적용 | 내부 네트워크 인프라 지도 유출 방지 |

#### 한줄 요약

- 이사 갈 땐 TTL 줄이고, 가짜 주소 사기당하지 않으려면 DNSSEC으로 도장 찍어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **TTL 전환 계획(TTL Transition Planning)**: 서버 IP 변경 시 끊김이 없게 며칠 전부터 TTL을 5분으로 줄여 캐시를 금방 비우게 만들고 이사 끝나면 다시 늘리는 꼼수 작전이다.

</details>

- **TTL 전환 계획** 원칙에 따라, 주소 변경 전엔 **TTL을 줄이고**, 상시 운영엔 **DNSSEC**으로 위변조를 막는 기조 확립함

#### 한줄 요약

- 장애 없는 이사를 위해선 TTL 조절이 필수고, 해킹 안 당하려면 DNSSEC이 필수다.
