## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스패닝 트리 프로토콜(STP)**: 스위치끼리 랜선을 두 가닥 꽂았을 때 빙빙 도는(루프) 대규모 네트워크 장애를 막기 위해, 평소엔 백업 선을 소프트웨어적으로 콱 틀어막아 버리는 프로토콜이다.
- **RSTP(Rapid STP)**: 구식 STP가 선 끊어지면 50초씩 멍때리니까, "제안-동의" 방식으로 1초 만에 백업 선을 팍 열어주는 쾌속 버전이다.
- **PVST+(Per-VLAN STP)**: 막아둔 백업 선이 아까우니까 "영업부는 1번 선, 개발부는 2번 선" 이런 식으로 VLAN마다 막는 선을 다르게 해서 대역폭을 뽕뽑는 꼼수 기술이다.
- **MAC 주소 테이블**: 스위치가 "이 주소는 저 포트" 하고 외워두는 장부인데, 루프가 돌면 프레임이 무한 순환하며 장부가 급격히 깜빡거리다(MAC Flapping) 스위치가 뻗어버린다.

</details>

- 정의: L2 망에서 중복 링크를 막아 브로드캐스트 루프를 원천 차단하는 **활성 트리(Active Tree) 구축 프로토콜**
- 배경: 랜선 끊어질까 봐 두 가닥씩 이중화해 놨더니, 프레임이 무한 순환하며 **MAC 장부를 박살 내고 스위치 CPU를 터트렸기 때문**

#### 한줄 요약

- 랜선을 두 개 꽂아도 루프 돌지 않게 하나를 콱 막아두고, 메인 선 끊어지면 그때서야 예비 선을 연다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **브리지 ID(Bridge ID)**: 라우터들끼리 "누가 반장(Root) 할래?" 하고 서열을 정할 때 내미는 명함으로, 앞쪽의 우선순위(Priority) 값이 낮을수록 무조건 짱이다.
- **경로 비용(Path Cost)**: 반장한테 가는 길이 여러 개일 때, "여긴 기가비트니까 비용 4, 여긴 10메가니까 비용 100" 하고 톨게이트비가 가장 싼 1등 길을 찾는 기준이다.

</details>

- **브리지 ID** 가장 낮은(우선순위가 좋은) 스위치를 전체 트리의 뿌리(Root Bridge)로 선출.
- **경로 비용** 계산하여 루트까지의 가장 빠른 길(Root Port)과 트래픽을 통과시킬 포트(Designated Port)를 결정.
- 구식 STP의 50초 딜레이를 개선한 **RSTP** 기반 제안•동의(Proposal/Agreement) 방식으로 토폴로지를 빛의 속도로 전환.

#### 한줄 요약

- 브리지 ID로 대장(Root)을 뽑고, 경로 비용으로 가장 빠른 길만 뚫어둔 채 나머지는 다 틀어막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트 포트(RP)**: 각 스위치가 대장(루트 브리지)한테 가는 가장 빠르고 싼 1등 포트다 (무조건 열림).
- **지정 포트(DP)**: 스위치끼리 연결된 선(링크) 구간에서 "내가 이 구간 트래픽 통과시킨다!" 하고 이긴 대장 포트다 (무조건 열림).
- **대체 포트(AP)**: 위 오디션에서 다 떨어진 찌끄레기 포트로, 루프 안 돌게 콱 막혀(Blocking) 있다가 메인 선 끊어지면 그때서야 열리는 예비 포트다.
- **BPDU(Bridge Protocol Data Unit)**: 스위치끼리 2초마다 "내가 대장이다!", "비용 얼마냐?" 하고 쑥덕거리며 주고받는 스패닝 트리 제어 전보다.

</details>

```text
[ 직관적 비교 기반 스패닝 트리 구조 ]

[ 대장 스위치 (Root Bridge) ] ── (BPDU 발송)
       │(DP)                      │(DP)
       │                          │
       │(RP)                      │(RP)
[ 일반 스위치 A ]            [ 일반 스위치 B ]
       │(DP)                      │(AP: 콱 막힘!)
       └────── (중복 랜선) ───────┘
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **루트 브리지** | **브리지 ID 제일 낮아서 대장 먹은 스위치**, 모든 포트가 무조건 DP로 열림 | 짱 (Root) |
| **루트 포트 (RP)** | 일반 스위치가 대장한테 갈 때 쓰는 **가장 빠른 1등 출구** | 무조건 열림 |
| **지정 포트 (DP)** | 연결된 랜선 구간에서 **트래픽 전달을 허가받은 구역 대표 포트** | 무조건 열림 |
| **대체 포트 (AP)** | 다 떨어지고 **루프 방지용으로 콱 막혀버린 잉여 포트** | 메인 끊기면 열림 |
| **BPDU** | 스위치끼리 서열 정하고 생존 신고하려고 **2초마다 쏘는 멀티캐스트 패킷** | L2 제어 메시지 |

#### 한줄 요약

- 대장(Root) 뽑고, 대장한테 가는 길(RP)과 구역 대표(DP)만 뚫어준 뒤, 남은 잉여(AP)는 콱 틀어막는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **BPDU 비교**: 받은 BPDU를 까보고 "1빠: 루트 ID 낮은 놈, 2빠: 경로 비용 싼 놈, 3빠: 송신 브리지 ID 낮은 놈, 4빠: 포트 ID 낮은 놈" 순서로 칼같이 서열을 따지는 과정이다.
- **루트 브리지 선출**: 스위치들이 서로 BPDU를 까보고, 전체 네트워크에서 브리지 ID(우선순위+MAC)가 제일 낮은 딱 한 놈을 대장으로 추대하는 오디션이다.

</details>

```text
[ STP 서열 정리 및 포트 차단 십자포화 흐름 ]
┌──────────────────────────────┐
│ 0. [BPDU 교환] 명함 뿌리기   │
│ (스위치끼리 2초마다 떠듦)    │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 1. [대장 뽑기] 루트 브리지   │
│ (브리지 ID 제일 낮은 놈 승리)│
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [1등 출구 찾기] RP 선출   │
│ (비루트 장비별 가장 싼 포트) │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [구간 대표 찾기] DP 선출  │
│ (각 랜선 구간의 대장 포트)   │
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [나머지 막기] AP 차단     │
│ (오디션 떨어진 포트 Blocking)│
└──────────────────────────────┘
```

### 동작 원리

1. BPDU 교환 및 비교: 2초마다 서로 명함(BPDU)을 교환하며 직관적 비교 서열(ID/비용) 비교.
2. 루트 브리지 선출: 브리지 ID가 가장 낮은 딱 1대의 스위치를 짱(Root)으로 올림.
3. 루트 포트(RP) 선출: 짱이 아닌 스위치들은 짱한테 가는 제일 싼 출구 딱 하나씩만 고름.
4. 지정 포트(DP) 선출: 각 연결된 랜선 구간마다 트래픽을 통과시킬 대표 포트 하나 고름.
5. 대체 포트(AP) 차단: 위에서 아무 타이틀도 못 딴 포트들은 루프 안 돌게 콱 틀어막음(차단).

#### 한줄 요약

- 명함 돌려서 대장(Root) 뽑고 $\to$ 출구(RP) 찾고 $\to$ 대표(DP) 뽑고 $\to$ 나머진 찢어버린다(AP 차단).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **STP, RSTP, PVST+**: (개요 참고)

</details>

| 스패닝 트리 방식 | **구식 STP (802.1D)** | **고속 RSTP (802.1w)** | **VLAN 분산 PVST+ (Cisco)** |
|:---|:---|:---|:---|
| 존재 목적 | 루프 방지 원조 국밥 | **끊어지면 1초 만에 팍 살림** | 놀고 있는 **막힌 포트 재활용** |
| 핵심 특징 | 타이머 기다리느라 **50초 멍때림** | 제안•동의 방식으로 **빛의 속도 절체** | VLAN마다 대장(Root)을 다르게 둬 부하 분산 |
| 한계점 | 요즘 시대엔 너무 느려터짐 | 구식 STP 장비 섞이면 걔 속도로 하향 평준화됨 | VLAN 개수만큼 계산해서 스위치 CPU 터짐 |

#### 한줄 요약

- 구식(STP)은 50초 걸리고, 신식(RSTP)은 1초 컷이며, PVST+는 부서별로 막는 선을 다르게 해 돈값을 뺀다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **루트 가드(Root Guard)**: 어디서 굴러먹던 싸구려 허브가 "내가 대장이다!" 하고 BPDU 쏘고 들어올 때, 가차 없이 그 포트를 찢어버려 대장 자리를 지키는 호위무사다.
- **PortFast / BPDU Guard**: PC 꽂는 포트에서 STP 계산하느라 30초 멍때리지 않고(PortFast) 꽂자마자 바로 켜주되, 혹시라도 그 포트로 BPDU가 들어오면 해킹으로 간주하고 칼같이 차단(BPDU Guard)하는 콤보다.
- **UDLD(단방향 링크 탐지)**: 광케이블 두 가닥 중 송신 선만 끊어지는 기묘한 장애가 나면, 막아둔 포트(AP)가 열리면서 루프 도는 대규모 네트워크 장애를 막기 위해 링크 자체를 죽여버리는 기능이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 외부 스위치가 **브리지 ID 속여서 자기가 대장 먹으려고 함** | 상위 스위치 포트에 **루트 가드(Root Guard)** 적용 | 근본 없는 놈이 대장(Root) 뺏어가는 통수 차단 |
| PC 꽂았는데 STP 계산하느라 **30초 뒤에나 켜져서 빡침** | PC 꽂는 포트는 꽂자마자 켜지는 **PortFast** 적용 | PC 부팅/DHCP 타임아웃 장애 깔끔히 해결 |
| 해커가 PC 포트에 스위치 꽂아서 **어거지로 루프 돌려버림** | PC 포트에 **BPDU Guard** 켜서 BPDU 오면 셧다운 시킴 | 비인가 스위치 연결 및 루프 테러 원천 차단 |
| 광케이블 하나만 끊어져서 막아둔 포트가 열리고 **루프 터짐** | 하드웨어적으로 단방향 감지하는 **UDLD** 적용 | 기묘한 물리 계층(단방향) 장애로 인한 대규모 네트워크 장애 방어 |

#### 한줄 요약

- 대장 뺏기지 않게 루트 가드 치고, PC 포트는 PortFast로 빨리 열되 BPDU 가드로 철벽 방어해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **무루프 이중화(Loop-Free Redundancy)**: 선은 두 개 꽂아서 안심은 하되, 평소엔 하나 콱 막아놔서 루프 도는 대규모 네트워크 장애는 막고 죽었을 때만 쓱 열어주는 쫄보 최적화 아키텍처다.

</details>

- **무루프 이중화** 기조 아래, 고속 수렴은 **RSTP**, 트래픽 분산(로드 밸런싱)은 **PVST+** 적용 기조 확립함

#### 한줄 요약

- 랜선 두 개 꽂았다고 좋아하지 말고 RSTP로 루프 막고 PVST+로 로드 밸런싱까지 세팅해야 진짜 엔지니어다.
