## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소프트웨어 대가(SW Cost)**: 사업 규모·작업량·단가·보정에 따른 비용.
- **원가 추정 체계(Cost Estimation System)**: 규모·작업량과 단가로 비용을 계산하는 체계.

</details>

- 정의/개념: 규모·작업량과 단가로 **소프트웨어 대가**를 계산하는 체계
- 배경/필요성: 투입 인원과 기간만으로 대가를 정하면 같은 기능을 오래 붙잡을수록 비용이 커지는 왜곡이 생기고 요구가 바뀔 때마다 증액 근거를 다투는 비용이 남으므로, 기능 규모와 작업량에 단가·보정을 곱하는 산정 체계를 계약 협상 앞에 두어 투입 기준을 산출물 기준으로 대체할 필요

#### 한줄 요약

- 기능 규모•작업량과 단가로 적정 예산을 산정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기능점수(Function Point, FP)**: 데이터·입력·출력·조회 기능의 규모 단위.
- **인공지능 사업**: 데이터•학습•검증•배포•맞춤화 사업.
- **추적 가능성**: 기능 기준선과 규모•기간•대가 증감의 관계를 연결할 수 있는 성질.

</details>

- 사용자 관점의 데이터·트랜잭션을 재는 **기능점수(FP)**
- 기능 기준선과 규모·대가 증감을 잇는 **추적 가능성**
- 작업 특성에 따라 방식을 고르는 **산정 방식 선택성**

#### 한줄 요약

- 사용자 기능 규모와 보정 요소를 반영해 대가를 산정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **기능 규모**: 데이터•입력•출력•조회 기능의 계수 규모.
- **내부 논리 파일(ILF)**: 대상 시스템이 관리하는 논리 데이터.
- **외부 연계 파일(EIF)**: 외부 시스템이 관리하고 대상이 참조하는 데이터.
- **외부 입력(EI)**: 내부 데이터•상태를 변경하는 입력 기능.
- **외부 출력(EO)**: 계산•가공 결과를 외부에 제공하는 기능.
- **외부 조회(EQ)**: 내부 변경 없이 조건에 맞는 정보를 반환하는 기능.
- **조정 계수(AF)**: 특성•복잡도를 규모•단가에 반영하는 계수.
</details>

```text
SW 대가
├── 사업범위
├── 기능 규모
├── 단가보정
├── 비용항목
└── 변경기준
```

| 구성요소 | 책임 |
|:---|:---|
| 사업범위 | 기획•개발•인공지능 사업 유형 정의 |
| 기능 규모 | **ILF·EIF·EI·EO·EQ** 측정 |
| 단가보정 | 엔지니어 단가와 **AF** 적용 |
| 비용항목 | 인건비•제경비•기술료•이윤 합산 |
| 변경기준 | 요구 변경의 추가 대가 산출 |

#### 한줄 요약

- 사업 유형•기능 규모와 단가 보정으로 대가를 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **투입공수**: 과업을 수행하는 데 필요한 인력 수와 투입 기간을 결합한 작업량.
- **기능 기준선**: 승인된 기능•규모의 대가•기간 조정 기준.
- **사업 유형•범위 정의**: 개발•운영•데이터•인공지능의 산정 대상과 책임 범위를 정하는 단계.
- **기능 규모•작업량 산정**: 기능점수와 과업별 투입공수를 측정하는 단계.
- **단가•보정 기준 적용**: 단가•복잡도•품질 보정 요소를 반영하는 단계.
- **비용 항목 검증**: 직접비•제경비•기술료 산식을 확인하는 단계.
- **변경 규모•대가 검증**: 기준선 대비 추가•삭제 기능으로 대가를 조정하는 단계.

</details>

```text
발주기관
   │ 1. 사업 유형•범위 정의
   ▼
수행기관
   │ 2. 기능 규모•작업량 산정
   │ 3. 단가•보정 기준 적용
   ▼
발주기관
   │ 4. 비용 항목 검증
   +---------------------+
   | 기능 기준선 변경 시 |
   +----------+----------+
              |
              v
   │ 5. 변경 규모•대가 검증
   ▼
수행기관
   │ 조정 대가 합의 반환
   ▼
발주기관
```

### 동작 원리

1. 사업 유형•범위 정의: 개발•운영•데이터•인공지능의 산정 대상을 확정한다.
2. 기능 규모•작업량 산정: 기능점수와 **투입공수** 측정
3. 단가•보정 기준 적용: 단가•복잡도•품질 보정 요소를 반영한다.
4. 비용 항목 검증: 직접비•제경비•기술료 산식을 확인한다.
5. 변경 규모•대가 검증: **기능 기준선** 대비 추가•삭제 기능을 반영한다.

#### 한줄 요약

- 범위•규모 측정부터 단가 보정•변경 검증까지 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **투입공수 방식**: 직무•등급•투입 기간을 인월로 산정하는 방식.
- **혼합 산정**: 기능은 FP, 데이터•모델 작업은 투입공수를 적용하는 방식.

</details>

| 산정 접근 | 투입공수 방식 | 기능점수 방식 |
|:---|:---|:---|
| 적용 범위 | **기능 규모 측정 곤란** 작업 | 기능이 식별되는 **개발·재구축** |
| 산정 근거 | 직무·등급·기간의 **투입공수** | **기능점수·보정계수·단가** |
| 한계 | **생산성·투입 적정성** 검증 부담 | **기능 식별 편차** |

- AI 사업은 기능점수와 투입공수의 **혼합 산정** 적용

#### 한줄 요약

- 기능 규모•작업량을 구분한 혼합 산정이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **주관적 식별**: 경계•기능 판정 근거 부족에 따른 FP 편차.
- **오차 범위**: 실제 비용이 추정값에서 벗어날 상•하한.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 요구 불명확 상태의 조기 견적 | **오차 범위** 명시 | **산정 위험** 감소 |
| 기능점수의 주관적 식별 | 경계·기능 근거와 **독립 검토** | **산정 일관성** 향상 |
| 추가 과업의 무상 수행 | 기준선과 **규모·기간·대가 동시 조정** | **일정·품질** 보호 |

#### 한줄 요약

- 산정 기준•FP 단가에 따른 개발비 근거를 명확히 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **변경 범위**: 기준선에서 추가•삭제된 기능을 식별한 조정 대상.

</details>

- 기능 식별 가능 시 **FP**, 불가능한 작업은 **투입공수**로 산정

#### 한줄 요약

- FP는 산정 근거를 남기는 대신 기능을 식별할 수 있는 사업에만 쓸 수 있으므로, 산정 방식의 선택은 정확성보다 근거를 두고 다툴 수 있는지에 달린다.
