## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **오픈소스 컴플라이언스(Open Source Compliance)**: 배포 소프트웨어의 오픈소스 구성•라이선스 의무•보안 취약점을 식별하고 이행 증거를 관리하는 공급망 준수 체계이다.
- **소프트웨어 자재명세서(Software Bill of Materials, SBOM)**: 소프트웨어를 구성하는 컴포넌트의 이름•버전•공급자•의존관계를 기록한 명세서.

</details>

- 정의/개념: **오픈소스 컴플라이언스**는 **SBOM**으로 구성•의무•취약점을 관리하는 공급망 준수 체계이다.
- 배경/필요성: 직접 의존성만으로는 전이 버전•배포 의무•신규 취약점을 추적하기 어렵다.

#### 한줄 요약
- **SBOM**으로 직접•전이 구성의 라이선스•취약점 추적

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **전이 의존성**: 직접 사용한 패키지가 다시 참조하여 제품에 포함되는 하위 구성요소 관계.
- **지속 갱신**: 새 빌드•패키지 변경•취약점 공개에 따라 SBOM과 위험 판정을 계속 최신화하는 관리.
- **소프트웨어 구성 분석(Software Composition Analysis, SCA)**: 소스와 빌드 산출물에서 직접•전이 오픈소스 구성요소와 라이선스•취약점 위험을 식별하는 분석.
- **패키지 URL(Package URL, PURL)**: 패키지 생태계•이름•버전•배포 위치를 표준 형식으로 식별하는 주소.
- **공통 취약점 및 노출(Common Vulnerabilities and Exposures, CVE)**: 공개된 보안 취약점에 공통 식별번호를 부여하는 체계.
- **취약점 악용 가능성 교환(Vulnerability Exploitability eXchange, VEX)**: 알려진 취약점이 특정 제품에 실제 영향을 미치는지와 조치 상태를 전달하는 문서.
- **구성 동일성**: SBOM의 패키지•버전•해시가 실제 배포 산출물과 일치하는 성질.
- **위험 분리성**: 라이선스 의무와 취약점 악용 가능성을 서로 다른 기준으로 판정하는 특성.

</details>

- 소스•빌드에서 직접•전이 요소를 찾는 **SCA** 기반 추적성이 핵심이다.
- **PURL**•버전•해시로 배포본을 검증하는 **구성 동일성**이 핵심이다.
- 라이선스와 CVE•VEX 판단을 나누는 **위험 분리성**이 핵심이다.

#### 한줄 요약
- **전이 의존성**까지 추적해 잠재 위험 식별

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **오픈소스 프로그램 사무국(Open Source Program Office, OSPO)**: 조직의 오픈소스 활용•기여•라이선스 준수 정책을 총괄하는 전담 조직.
- **라이선스 의무**: 고지•저작권 표시•소스 제공 등 배포 조건에 따라 이행해야 하는 요구.

</details>

```text
                    [정책•OSPO]
                         |
                    [탐지•SBOM]
                         |
              +----------+----------+
              |                     |
         [법률 검토]            [보안 분석]
              |                     |
              +----------+----------+
                         |
                    [배포 증거]
```

선의 의미: 정책•OSPO 아래 탐지•SBOM을 중심으로 법률 검토와 보안 분석이 분리되고, 두 검토 결과가 배포 증거에 결합되는 공급망 준수 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 정책•OSPO | **오픈소스 프로그램 사무국**이 허용 라이선스•예외 기준 수립 |
| 탐지•SBOM | **SCA**로 실제 빌드의 구성•관계 기록 |
| 법률 검토 | **라이선스 의무** 판정 |
| 보안 분석 | **CVE** 도달성과 **VEX** 상태 판정 |
| 배포 증거 | 고지•소스•SBOM•승인 기록 보존 |

#### 한줄 요약
- **라이선스 의무•취약점 영향**을 분리 검증

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소프트웨어 패키지 데이터 교환(Software Package Data Exchange, SPDX)**: 소프트웨어 구성요소•라이선스•저작권과 공급망 정보를 교환하는 표준 형식.
- **SBOM•구성 동일성 분석**: 실제 배포본의 패키지•버전•해시•관계를 명세와 대조하는 단계.
- **라이선스•취약점 조치 판정**: 배포 의무와 취약점 도달성•조치 상태를 각각 결정하는 단계.
- **고지•소스•VEX 배포 준비**: 예외 심사와 법적•보안 조치를 마치고 출시 자료를 구성하는 단계.
- **신규 취약점•구성 변경 대조**: 운영 중 SBOM을 신규 CVE와 패키지 변경에 다시 대조하는 단계.

</details>

```text
개발팀
   │ 소스•빌드 산출물 전달
   ▼
구성 분석
   │ 1. SBOM•구성 동일성 분석
   │    SBOM•구성 분석 결과 제출
   ▼
준수 심사
   │ 2. 라이선스•취약점 조치 판정
   │    라이선스•취약점 조치 요청
   ▼
개발팀
   │ 3. 고지•소스•VEX 배포 준비
   │    제품•SBOM•VEX 배포
   ├──────────────────────┐
   │ 운영 중 취약점 감시 │
   └──────────┬───────────┘
   ▼
운영팀
   │ 신규 취약점•구성 변경 통보
   ▼
구성 분석
   │ 4. 신규 취약점•구성 변경 대조
   ▼
```

### 동작 원리

1. **SBOM•구성 동일성 분석**: **SPDX** 형식의 버전•해시•관계로 실제 배포 구성을 확인한다.
2. **라이선스•취약점 조치 판정**: 배포 의무와 CVE 도달성•VEX 상태를 판정한다.
3. **고지•소스•VEX 배포 준비**: 예외 심사와 의무 이행 후 출시를 승인한다.
4. **신규 취약점•구성 변경 대조**: **지속 갱신**으로 SBOM을 신규 CVE•변경과 대조한다.

#### 한줄 요약
- **구성 동일성 분석•신규 취약점 대조** 반복

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **라이선스 목록**: 제품에 포함된 오픈소스의 라이선스•저작권 표시와 배포 의무 정보를 정리한 목록.

</details>

| 오픈소스 공급망 정보 | 라이선스 목록 | SBOM | VEX |
|:---|:---|:---|:---|
| 적용 기준 | **라이선스 목록**은 저작권 표시•의무 고지 | **SBOM**은 제품 구성 공개 | **VEX**는 취약점 영향•조치 상태 통지 |
| 핵심 특징 | 라이선스•고지 정보 | 구성•버전•관계 정보 | 취약점 영향•조치 정보 |
| 한계 | 실제 구성 누락 가능성 | 의무•악용 가능성 미판정 | 근거 없는 상태 오판 |

#### 한줄 요약
- 구성은 **SBOM**, 법적 의무는 라이선스, 영향은 **VEX** 전달

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SBOM-실제 빌드 불일치**: 명세에 기록된 컴포넌트와 최종 배포 이미지의 실제 파일•버전이 다른 문제.
- **취약점 오탐**: 패키지 버전만 일치하지만 취약 코드가 포함•도달되지 않아 실제 악용 가능성이 없는 경고.
- **미국 사이버보안•인프라보안국(Cybersecurity and Infrastructure Security Agency, CISA) 최소 요소**: SBOM 자동 교환을 위해 요구되는 기본 데이터 필드와 관행.
- **SPDX 3.0**: 소프트웨어 구성과 공급망 정보를 구조화해 교환하는 표준 형식의 버전.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SBOM-실제 빌드 불일치 | 빌드에서 PURL•버전•해시를 추출해 SBOM 대조 | 누락된 **전이 의존성** 식별 |
| 라이선스•취약점 판단 혼동 | **라이선스 의무**와 **취약점 오탐** 여부를 분리 | 출시 판정의 정확성 향상 |
| 출시 후 신규 CVE 발생 | SBOM과 취약점 피드를 대조해 **VEX** 갱신 | 영향 제품의 신속한 선별 |
| 최소 요소•형식 불일치 | **CISA 최소 요소**와 **SPDX 3.0** 검증 | 정보 교환 상호운용성 확보 |

#### 한줄 요약
- **취약점 오탐•라이선스 판정**은 법무•개발 교차 검토

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **공급망 추적성**: 제품에서 컴포넌트•공급자•라이선스•취약점•수정 버전까지 역으로 연결할 수 있는 성질.

</details>

- **공급망 추적성**을 위해 구성은 **SBOM**, 법적 의무는 라이선스 심사, 실제 취약점 영향은 **VEX**로 전달한다.

#### 한줄 요약
- **SBOM**•**VEX**를 지속 갱신해 공급망 위험 추적
