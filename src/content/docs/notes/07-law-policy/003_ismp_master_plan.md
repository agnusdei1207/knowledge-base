## 미리 알고가기

- **정보시스템 마스터 계획(Information System Master Plan, ISMP)**: 특정 정보시스템 구축 사업을 추진하기 전에 비즈니스와 기술 요건을 상세히 정의하여 발주 및 계약 기준을 수립하는 활동
- **정보화 전략 계획(Information Strategy Plan, ISP)**: 조직의 중장기 정보화 투자 비전과 추진 과제 로드맵을 설계하는 상위 수준의 기획 활동
- **제안 요청서(Request for Proposal, RFP)**: 발주기관이 수주업체들에게 사업 범위, 예산, 기술 사양 및 제안 요령을 명시하여 발송하는 공식 문서
- **기능점수(Function Point, FP)**: 소프트웨어가 제공하는 기능적 규모를 데이터 기능과 트랜잭션 기능 기준으로 측정하여 정량화하는 표준 산정 단위
- **요구사항 기준선(Requirement Baseline)**: 프로젝트 수행 중 범위 변경이나 추가 대가를 산출할 때 판단 기준이 되는 합의된 요구사항 명세서
- **약어 읽기·표기**: ISMP는 ‘아이에스엠피’, ISP는 ‘아이에스피’, RFP는 ‘알에프피’, FP는 ‘에프피’로 읽으며 영문 정식명의 머리글자로 발주 계획·전략·문서·규모를 구분함
- **도식 기호(-->)**: ‘다음 단계’로 읽고 실선 화살표는 요구사항이 규모·예산·RFP로 구체화됨을 뜻함

## Ⅰ. 개요

- 정의/개념: 구축사업의 요구·규모·예산을 정하는 발주 계획
- 기존 한계: 불명확한 과업으로 요구 누락·대가 분쟁 발생

### 쉽게 이해하기 (학습용)
- 한 시스템을 새로 개발하기로 결정한 뒤, 업체 선정과 계약 전에 구체적인 작업 범위와 적정 비용을 계산하는 활동임

## Ⅱ. 특징

- **요구 상세화**: 기능·비기능·연계 범위를 확정한다
- **규모·대가 산정**: FP와 비용 근거로 예산을 정한다
- **발주 기준선**: 요구사항을 RFP·계약 기준으로 전환한다

### 쉽게 이해하기 (학습용)
- 중장기 방향만 보여주는 전략 계획과 달리, 개발자가 구현해야 하는 상세 버튼, 화면 구성, 보안 규격 등을 모두 문서화하여 개발 도중 계약 분쟁이 생기지 않도록 함

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    G[사업 목표] --> R[요구사항]
    R --> A[목표 구조]
    A --> S[규모·예산]
    S --> P[RFP·이행방안]
```

| 설계 요소 | 설명 |
|:---|:---|
| 사업 목표 | 구축 목적·대상 업무·산출물 정의 |
| 요구사항 목록 | 기능·품질·보안·연계 요구 정리 |
| 규모 산정 | FP 기반 개발 규모 계산 |
| 이행 방안 | 범위·일정·조직·위험 대응 수립 |
| RFP | 요구·계약·평가 기준 확정 |

> 요약: 요구사항을 발주 문서로 체계화함

### 쉽게 이해하기 (학습용)
- 구축할 시스템의 목표 설정부터 기능 사양서 작성, 소프트웨어 규모 측정, 그리고 최종 제안 요청서 작성까지 사업 발주에 필요한 요소들로 구성됨

## Ⅳ. 원리 및 절차 흐름도

```mermaid
flowchart LR
    A[사업 범위 설정] --> B[현황·요구 분석]
    B --> C[목표 구조 설계]
    C --> D[규모·비용 산정]
    D --> E[이행방안 수립]
    E --> F[RFP 작성]
```

| 절차 | 핵심 활동 |
|:---|:---|
| 사업 범위 설정 | 목표·대상 업무·경계 확정 |
| 현황·요구 분석 | 기능·비기능·연계 요건 도출 |
| 목표 구조 설계 | 응용·데이터·기술 구조 구체화 |
| 규모·비용 산정 | FP·직접경비로 예산 산정 |
| 이행방안 수립 | 일정·조직·위험 대응 확정 |
| RFP 작성 | 요구·계약·평가 기준 명시 |

### 쉽게 이해하기 (학습용)
- 개발 범위를 확정하고 화면과 기능을 분석한 뒤, 전체 시스템 구조를 설계하고 개발 난이도를 측정하여 적절한 공사 비용을 담은 제안 요청서를 작성함

## Ⅴ. ISMP·ISP 비교

| 비교 기준 | ISMP | ISP |
|:---|:---|:---|
| 적용 기준 | 개별 사업 발주 전 상세화 시 | 중장기 투자 계획 수립 시 |
| 핵심 특징 | 요구·규모·예산·RFP | 비전·과제·투자 로드맵 |
| 한계 | 전사 전략 관점 부족 | 발주 요구·대가 상세 부족 |

> 요약: ISP는 투자 방향, ISMP는 발주 범위를 정함

### 쉽게 이해하기 (학습용)
- ISP는 중장기 정보화 투자 방향을 정하고, ISMP는 특정 시스템 구축 전에 상세 발주 규격을 작성함

## Ⅵ. 실무 사례

1. 공공 구축사업: **요구 기준선**으로 범위 확정

### 쉽게 이해하기 (학습용)
- 화면에서 입력받는 값과 저장 규칙을 구체적인 표 형태로 기술하여 개발자가 자의적으로 해석하지 않도록 사양을 확정함

## Ⅶ. 결론

- 구축 위험 통제를 위해 요구·규모를 검토하여 **ISMP** 활용

### 쉽게 이해하기 (학습용)
- 합의된 요구사항 기준선과 표준 단가를 기준으로 개발 비용을 투명하게 정해 불필요한 사업 지연과 발주 분쟁을 근본적으로 차단해야 함
