## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISMP**: 단일 정보시스템 사업의 요구·구조·비용·발주 조건을 상세화하는 계획.
- **기능점수(FP)**: 사용자 관점의 데이터·트랜잭션 기능으로 SW 규모를 측정하는 방식.
- **RTM**: 요구사항과 설계·구현·시험의 연결을 추적하는 매트릭스.

</details>

- 정의/개념: 단일 사업을 발주 가능한 수준으로 구체화하는 **실행 마스터플랜**
- 배경/필요성: 모호한 발주 요구는 범위 해석 차이로 **과업 변경·검수 분쟁 증가**

#### 한줄 요약
- ISMP는 단일 사업의 요구·구조·비용을 구체화해 RFP를 만든다.

## Ⅱ. 특징

- 기능·비기능을 시험 가능하게 만드는 **상세 요구사항**
- 합격 조건을 사전에 정하는 **수용 기준**
- ILF·EIF·EI·EO·EQ 기반 **기능점수(FP)**
- 요구부터 시험까지 연결하는 **RTM 추적성**
- 목표 구조와 용량을 검증하는 **아키텍처·사이징**
- 계약 경계를 명확히 하는 **RFP 상세화**

#### 한줄 요약
- 요구, 수용 기준, FP, RTM, 아키텍처, RFP 상세화가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── ISMP 체계 ──────────────┐
│                                      │
├── [사업 개요·범위]                   │
├── [상세 요구·수용 기준]              │
├── [목표 아키텍처·사이징]             │
├── [FP·사업비 산정]                   │
└── [이행 방안·RFP]                    │
```

| 구성요소 | 책임 |
|:---|:---|
| **사업 개요·범위** | 목적·경계·이해관계자·제약 확정 |
| **상세 요구·수용 기준** | 기능·품질·보안·연계 합격 조건 정의 |
| **목표 아키텍처·사이징** | 데이터·응용·기술 구조와 용량 설계 |
| **FP·사업비 산정** | SW 규모와 도입·운영 비용 산출 |
| **이행 방안·RFP** | 일정·평가·계약·검수 기준 문서화 |

#### 한줄 요약
- 범위, 요구, 구조, 비용, RFP의 5개 요소로 구성된다.

## Ⅳ. 흐름도

```text
[발주기관]
     │
     └──────── 사업 상세화 요청
                 │
                 ▼
            [ISMP 조직]
                 │ 1. 사업 범위·경계 확정
                 │ 2. 상세 요구·수용 기준 정의
                 │ 3. 목표 구조·용량 설계
                 │ 4. FP·총사업비 산정
                 │ 5. 이행 방안·RFP 확정
                 └──────── 발주 자료 반환
```

**동작 원리**

1. **사업 범위·경계 확정**: 대상 기능·연계·이해관계자·제약 정의
2. **상세 요구·수용 기준 정의**: 측정 가능한 요구와 시험 조건 확정
3. **목표 구조·용량 설계**: 구현 가능성과 성능·복원력 검증
4. **FP·총사업비 산정**: 기능 규모와 HW·SW·경비 통합 계산
5. **이행 방안·RFP 확정**: RTM·평가·계약·검수 조건 문서화

#### 한줄 요약
- 범위, 요구, 구조, 비용, RFP 순으로 발주 자료를 만든다.

## Ⅴ. 종류 및 비교

| 비교 항목 | ISP | ISMP |
|:---|:---|:---|
| 핵심 목적 | 중장기 **투자 방향** | 단일 사업 **발주 상세화** |
| 대상 범위 | 전사·사업 영역의 다수 과제 | 특정 정보시스템 과제 |
| 요구 수준 | 전략·기능 수준 | 기능·데이터·연계·품질 수준 |
| 비용 산정 | 개략 투자 규모 | FP·도입비 기반 상세 규모 |
| 주요 산출물 | 전략 과제·로드맵 | RFP·RTM·FP·수용 기준 |
| 다음 단계 | 과제별 ISMP·예산 | 입찰·계약·구축 사업 |

#### 한줄 요약
- ISP는 투자할 과제, ISMP는 발주하고 구축할 방법을 정한다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| 모호한 요구로 범위·검수 분쟁 | 측정 가능한 **수용 기준** 명시 |
| FP 누락·중복으로 사업비 왜곡 | 기능 경계와 **FP 산정 증적** 검토 |
| 예산을 초과하는 요구 전수 수용 | MoSCoW 기반 **범위 기준선** 확정 |
| 요구와 시험 항목의 연결 단절 | 요구 ID 기반 **RTM 추적** |
| 목표 구조의 구현·용량 타당성 부족 | 아키텍처·부하 **사전 검증** |

#### 한줄 요약
- 수용 기준, FP 증적, 범위 기준선, RTM, 사전 검증을 적용한다.

## Ⅶ. 결론

- 범위·수용 기준·FP 근거가 검증되면 **RFP 확정·본 사업 발주**

#### 한줄 요약
- 측정 가능한 요구와 적정 비용을 입증한 뒤 구축 사업을 발주한다.
