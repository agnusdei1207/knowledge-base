## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **전자정부 표준프레임워크(eGovernment Standard Framework, eGovFrame)**: 공공 정보시스템 개발에 필요한 실행환경•개발환경•공통 컴포넌트와 표준 구조를 제공하는 오픈소스 개발 기반이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **표준 개발 기반(English, English)**: 특정 업무 완제품이 아니라 여러 공공 시스템이 공통 구조와 기능을 재사용하도록 제공하는 기술 기반이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- 정의/개념: **전자정부 표준프레임워크(eGovFrame)**는 공공 시스템에 표준 구조•기능을 제공하는 **표준 개발 기반**이다.
- 배경/필요성: 기관별 독자 개발은 공통 기능 중복•구조 불일치•사업자 종속을 유발한다.

#### 한줄 요약
- 공공 시스템에 Spring 기반 공통 개발 구조를 제공한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **스프링 프레임워크(English, Spring Framework)**: 자바 애플리케이션의 객체 관리•웹•데이터 처리를 지원하고 전자정부 표준프레임워크 실행환경의 기반이 되는 프레임워크이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **개방형 표준(English, English)**: 공개된 소스•인터페이스•가이드로 특정 사업자의 독점 구현 의존을 줄이는 방식이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **공통 컴포넌트(English, English)**: 로그인•권한•게시판•파일 처리 등 반복 업무 기능을 표준 방식으로 재사용하도록 제공하는 모듈이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- **스프링 프레임워크** 기반 공개 구조로 종속을 줄이는 **개방형 표준**이 핵심이다.
- **공통 컴포넌트**와 표준 확장점으로 기능을 재사용한다.

#### 한줄 요약
- **개방형 표준**으로 사업자 종속을 줄이고 참여 기반을 확대한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **실행환경(English, English)**: 애플리케이션 실행 시 화면•업무 로직•데이터 처리를 지원하는 공통 라이브러리와 런타임 서비스이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **개발환경(English, English)**: 소스 구현•빌드•디버깅•시험•형상 관리를 지원하는 개발자 도구 모음이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **운영환경(English, English)**: 배포된 애플리케이션의 모니터링•배치•장애 대응을 지원하는 도구 체계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **관리환경(English, English)**: 설정•변경•운영 지표를 관리하는 도구 체계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **지원체계(English, English)**: 표준프레임워크의 교육•기술지원•호환성 확인•버전 및 생태계 관리를 제공하는 조직과 절차이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **웹 애플리케이션 서버(Web Application Server, WAS)**: 웹 요청을 받아 업무 로직을 실행하고 애플리케이션 런타임 서비스를 제공하는 서버이며, 이를 통해 실질적인 작동 방식과 사용 맥락을 구체화한다.

</details>

```text
                       [지원체계]
                            |
[개발환경] ----- [실행환경] ----- [운영•관리]
                       |
                [공통컴포넌트]
```

선의 의미: 실행환경은 개발환경에서 구현한 애플리케이션과 공통컴포넌트의 런타임 기반이며 운영•관리 도구의 관리 대상이고, 지원체계는 이 구성 전체의 기술 가이드와 호환성을 뒷받침하는 정적 프레임워크 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 개발환경 | **개발환경**의 소스 구현•빌드•형상 관리 도구 |
| 실행환경 | **실행환경**의 화면•연계•데이터 런타임 서비스 |
| 운영•관리 | **운영환경**과 **관리환경**의 모니터링•변경 관리 도구 |
| 공통컴포넌트 | **공통 컴포넌트**의 로그인•게시판 등 재사용 모듈 |
| 지원체계 | **지원체계**의 기술 가이드•제품 호환성 확인 |

#### 한줄 요약
- **개발환경**•**실행환경**•**운영환경**과 공통 컴포넌트•지원체계를 구성한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **공통 구조 적용(English, English)**: 업무 요구를 계층•인터페이스•예외•보안 등 표준프레임워크 아키텍처에 맞추는 과정이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **컴포넌트 재사용 검토(English, English)**: 새로 개발하기 전에 요구 기능과 기존 공통 컴포넌트의 적합성•변경 범위를 확인하는 절차이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **WAS 호환성(English, English)**: 표준프레임워크의 라이브러리•자바 규격과 배포 대상 WAS의 지원 버전이 맞는지 확인하는 조건이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **버전•구조•공통컴포넌트 지정(English, English)**: 지원 버전•공통 구조•재사용 범위•확장 방식을 정하는 단계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **표준 확장점•업무 로직 구현(English, English)**: 공통 기능은 재사용하고 기관 업무는 허용된 확장 영역에 개발하는 단계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **아키텍처•제품 호환성 검증(English, English)**: 라이브러리•WAS•연계 제품의 버전과 충돌을 확인하는 단계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

```text
사업 조직
   │ 사업•기술•표준 요구 전달
   ▼
아키텍트
   │ 1. 버전•구조•공통컴포넌트 지정
   │    설계 기준 전달
   ▼
개발팀
   │ 2. 표준 확장점•업무 로직 구현
   │    소스•빌드 증거 제출
   ▼
아키텍트
   │ 3. 아키텍처•제품 호환성 검증
   │    운영 전환 요청
   ▼
운영팀
   │ 운영 전환•관측 결과 보고
   ▼
사업 조직
```

### 동작 원리

1. **버전•구조•공통컴포넌트 지정**: **공통 구조 적용**과 **컴포넌트 재사용 검토** 결과를 확정한다.
2. **표준 확장점•업무 로직 구현**: 공통 기능은 재사용하고 기관별 업무 로직은 확장 영역에 구현한다.
3. **아키텍처•제품 호환성 검증**: **WAS 호환성**과 라이브러리•연계 제품의 충돌을 확인한다.

#### 한줄 요약
- **버전•구조•공통컴포넌트 지정** 후 **아키텍처•제품 호환성 검증**을 수행한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **표준 프레임워크(English, English)**: 여러 공공 시스템이 공통 구조•규칙•컴포넌트를 재사용하도록 제공하는 개발 기반이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **개별 개발 프레임워크(English, English)**: 특정 사업 요구에 맞춰 독립적인 구조와 기술 조합으로 구성한 개발 기반이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

| 판단 기준 | 표준 프레임워크 | 개별 개발 프레임워크 |
|:---|:---|:---|
| 적용 기준 | **표준 프레임워크**는 공공 표준 준수 필요 | **개별 개발 프레임워크**는 독립 구조 필요 |
| 핵심 특징 | 공개 표준과 **공통 컴포넌트** | 사업별 독립 기술 구조 |
| 한계 | 버전•호환성 관리 필요 | 중복 개발•사업자 종속 가능 |

#### 한줄 요약
- 공공 표준 필요 시 **표준 프레임워크**의 공통 구조•컴포넌트를 재사용한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **자카르타 엔터프라이즈 에디션(Jakarta Enterprise Edition, Jakarta EE)**: 기업용 자바 응용의 웹•데이터•트랜잭션 응용 프로그래밍 인터페이스(Application Programming Interface, API)를 정의한 표준이며, 이를 통해 실질적인 작동 방식과 사용 맥락을 구체화한다.
- **자바 개발 키트(Java Development Kit, JDK)**: 자바 소스의 컴파일•실행•디버깅에 필요한 개발 도구와 런타임을 묶은 배포판이며, 이를 통해 실질적인 작동 방식과 사용 맥락을 구체화한다.
- **버전 호환성(English, English)**: JDK•Spring•Jakarta EE•WAS•라이브러리 버전 조합이 맞지 않아 빌드•실행이 실패하는 문제이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 실행환경•JDK 버전 불일치 | **JDK**와 실행환경 지원 조합 검증 | 배포•실행 오류 예방 |
| 개발환경•WAS 버전 불일치 | **Jakarta EE**•Servlet•**WAS** 조합 검증 | 개발•배포 호환성 확보 |
| 공통컴포넌트의 무분별한 수정 | 표준 확장점과 변경 영향 형상관리 | 업그레이드 가능성 유지 |
| 업무와 무관한 일률적 표준 적용 | **버전 호환성**과 재사용 이익•유지보수 역량 평가 | 불필요한 복잡성 억제 |

#### 한줄 요약
- 외부 라이브러리와 **버전 호환성**을 확인한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **사업자 종속 완화(English, English)**: 공개된 공통 구조•소스•가이드로 다른 사업자가 시스템을 인수•유지보수할 수 있게 하는 효과이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **도입과 준수의 구분(English, English)**: 라이브러리를 사용했다는 사실만으로 표준 구조•보안•품질을 자동 충족하지 않으며 아키텍처와 개발 규칙 준수를 별도 검증해야 한다는 관계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- **도입과 준수의 구분**에 따라 공통 기능 재사용 시 **eGovFrame**, 독립 구조 시 **개별 개발 프레임워크**를 선택한다.

#### 한줄 요약
- **사업자 종속 완화**를 위해 표준 릴리즈와 호환성을 검증 체계 적용 및 준수 적용.
