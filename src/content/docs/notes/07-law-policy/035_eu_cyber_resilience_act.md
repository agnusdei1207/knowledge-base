## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **EU CRA**: EU 시장의 디지털 요소 제품에 생애주기 보안 의무를 부과하는 규정.
- **디지털 요소 제품**: 소프트웨어나 원격 처리 기능을 포함한 연결 제품.

</details>

- 정의/개념: 디지털 요소 제품의 설계·지원 보안을 의무화한 **제품보안 규정**
- 배경/필요성: 스마트폰, IoT 기기, 방화벽, 산업용 제어기기 등 하드웨어와 소프트웨어가 결합된 '디지털 요소 제품(Products with Digital Elements)'이 보안 설계 없이 출시되어, 공급망에 유입된 취약점이 전 세계 수십억 개 기기로 전파되고 제조사의 사후 패치 지원 방치로 대규모 봇넷(Botnet) 및 랜섬웨어 공격에 무방비 노출되는 치명적 결함이 발생함에 따라, 유럽연합 사이버 복원력 법(EU Cyber Resilience Act)에 의거하여 EU 시장에 출시되는 모든 유·무선 연결 디지털 제품에 대해 설계 단계부터 보안 내재화(Security by Design/Default), 소프트웨어 자재명세서(SBOM) 제공, 제품 수명주기 전반(최소 5년)의 취약점 무료 보안 패치 제공 및 24시간 이내 악용 취약점 의무 보고를 법제화하여 **글로벌 하드웨어/소프트웨어 제품 보안성 강화, 공급망 취약점의 선제적 제거 및 안전한 디지털 단일 시장 조성**을 달성할 필요

#### 한줄 요약
- CRA는 디지털 요소 제품의 출시 전 보안과 지원기간 취약점 처리를 규율한다.

## Ⅱ. 특징

- 설계부터 지원 종료까지의 **생애주기 보안성**
- 제품 중요도에 따른 **위험 비례 적합성 평가**
- 제조·수입·유통의 **공급망 책임성**
- 기본 보안 설정과 공격면 축소의 **보안 설계**
- 취약점 수신·분석·패치의 **취약점 처리 절차**
- 출시 후 부적합을 통제하는 **시장감시·회수**

#### 한줄 요약
- 생애주기, 위험 비례, 공급망, 보안 설계, 취약점 처리가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── CRA 제품보안 체계 ──────────────┐
│                                             │
│           [적합성 평가기관]                 │
│                  └── [제조자]               │
│                      ├── [수입자]           │
│                      ├── [유통업자]         │
│                      └── [이용자]           │
│           [시장감시기관]                    │
└─────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **제조자** | 위험평가·보안설계·문서·지원 책임 |
| **적합성 평가기관** | 제품 등급별 독립 평가 수행 |
| **수입자** | 제3국 제조자·표시·문서·부적합 확인 |
| **유통업자** | 표시·보관조건·시장 공급 확인 |
| **시장감시기관** | 보고·시정·판매 제한·회수 감독 |

#### 한줄 요약
- 제조자가 출시 전 보안설계부터 지원기간 취약점 처리까지 지고 수입자·유통업자가 그 문서와 표시를 확인하는 배치여서, 이용자가 제품마다 안전을 스스로 판별하던 부담이 공급망 앞단의 적합성 평가로 옮겨지고 시장감시기관이 사후 회수를 맡는다.

## Ⅳ. 흐름도

```text
[제품 기획·개발]
     │
     │ 1. 위험평가·보안 요구 설계
     ▼
[제조자]
     │ 2. 기술문서·SBOM·지원기간 확정
     │ 3. 등급별 적합성 평가·CE 표시
     │ 4. 출시 후 취약점·사고 감시·보고
     │ 5. 패치·시정·판매 제한·회수
     ▼
[이용자·시장감시기관]
     │
     └──────── 조치 결과 반환
```

**동작 원리**

1. **위험평가·보안 요구 설계**: 사용·연결·공격면·기본 설정 분석
2. **기술문서·SBOM·지원기간 확정**: 통제·부품·패치 책임 기록
3. **등급별 적합성 평가·CE 표시**: 자체·제3자 경로로 요구 충족 입증
4. **출시 후 취약점·사고 감시·보고**: 악용·사고 정보의 적시 통지
5. **패치·시정·판매 제한·회수**: 위험 수준에 맞는 시장조치 수행

#### 한줄 요약
- 보안 설계, 문서, 적합성, 사후 감시, 시정 순으로 제품을 통제한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 기본 제품 | 중요 제품 Class I | 중요 제품 Class II |
|:---|:---|:---|:---|
| 위험 수준 | 일반 디지털 요소 제품 | 핵심 보안 기능·위험 제품 | 더 높은 위험의 중요 제품 |
| 평가 경로 | 일반 적합성 절차 | 조건에 따른 **제3자 평가** | 강화된 **제3자 적합성 평가** |
| 문서·시험 | 필수 요구 증명 | 등급·표준별 강화 | 독립 평가 증거 강화 |
| 운영 주의 | 위험 과소평가 방지 | 적용 표준·분류 확인 | 평가 누락 시 출시 제한 |

#### 한줄 요약
- 제품 위험이 높을수록 적합성 평가의 독립성과 증거를 강화한다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| 제품 등급 오류로 평가 경로 누락 | 용도·기능 기반 **적합성 경로** 문서화 |
| 구성 부품 취약점 영향 파악 지연 | 버전·의존성의 **SBOM 계보** 유지 |
| 보고 절차 부재로 법정 기한 초과 | 조기경보·후속 통지 **런북** 운영 |
| 지원기간과 패치 역량 불일치 | 지원 자원·종료 조건의 **사전 검증** |
| 유통 단계에서 부적합 정보 단절 | 제조·수입·유통 **시정 정보 인계** |

#### 한줄 요약
- 평가 경로, SBOM, 보고 런북, 지원 역량, 정보 인계로 제품 위험을 통제한다.

## Ⅶ. 결론

- 소프트웨어와 연결 기기의 보안 책임을 최종 소비자에서 제조사 및 공급망으로 전면 전환하여 전 세계 하드웨어/소프트웨어 제조업계의 패러다임을 바꾼 **유럽연합 사이버 복원력 법(EU Cyber Resilience Act / Security by Design & SBOM / Vulnerability Handling & 5-Year Patching / CE Mark)의 글로벌 제품 보안 최고 표준**으로 확고히 자리 잡았으며, 미국 행정명령(EO 14028) 및 글로벌 공급망 보안 인증 규범으로 정착되는 가운데, 실무 CRA 준수 및 제품 개발 시에는 **제품 기획 단계부터 중요도 등급(Class I/II) 판정 및 제3자 적합성 평가(CE 마크) 경로 확보, 표준 형식(SPDX/CycloneDX)의 정밀한 SBOM 생성 및 자동화된 취약점 스캔 연계, 악용 가능한 취약점 식별 시 24시간 이내 ENISA 보고 및 최소 5년간의 보안 패치 자동 배포 인프라 완비**를 결합하여 완벽한 제품 신뢰성과 글로벌 수출 경쟁력을 완성

#### 한줄 요약
- 출시 전 적합성을 입증하고 공표한 지원기간 동안 취약점을 처리한다.
