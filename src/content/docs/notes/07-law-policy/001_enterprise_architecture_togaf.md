## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **EA**: 경영 전략과 비즈니스·데이터·응용·기술 구조를 정렬하는 전사 청사진.
- **TOGAF**: EA 개발 방법과 콘텐츠·거버넌스를 제공하는 개방형 프레임워크.

</details>

- 정의/개념: 전략과 IT 자산을 4대 도메인으로 정렬하는 **전사 아키텍처**
- 배경/필요성: 부서별로 따로 구축하면 같은 데이터와 기능이 **중복·사일로**로 쌓여 연계할 때마다 개별 협의와 재개발 비용이 되풀이되므로, 비즈니스·데이터·응용·기술 4대 도메인의 공통 청사진과 표준을 개별 사업 위에 두어 사업마다 반복되던 구조 협의를 한 번 정한 기준의 참조로 대체할 필요

#### 한줄 요약
- EA는 전략과 4대 도메인을 정렬하고 TOGAF로 지속 변화시킨다.

## Ⅱ. 특징

- 전략과 업무 구조를 정의하는 **비즈니스 아키텍처(BA)**
- 정보 자산과 흐름을 정의하는 **데이터 아키텍처(DA)**
- 서비스와 연계를 정의하는 **애플리케이션 아키텍처(AA)**
- 플랫폼과 표준을 정의하는 **기술 아키텍처(TA)**
- 요구를 중심으로 반복하는 **TOGAF ADM**
- 원칙·표준·빌딩 블록의 **아키텍처 저장소**

#### 한줄 요약
- BA·DA·AA·TA 정렬, ADM 순환, 저장소 자산화가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌────────────── 전사 아키텍처 ──────────────┐
│                                          │
│  [아키텍처 거버넌스]                     │
│        │                                 │
│  [비즈니스 아키텍처]                     │
│    ├── [데이터 아키텍처]                 │
│    └── [애플리케이션 아키텍처]           │
│        └── [기술 아키텍처]               │
│                                          │
│  [아키텍처 저장소]                       │
└──────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **비즈니스 아키텍처** | 전략·조직·기능·프로세스 정의 |
| **데이터 아키텍처** | 데이터 구조·흐름·소유권 정의 |
| **애플리케이션 아키텍처** | 서비스·컴포넌트·연계 정의 |
| **기술 아키텍처** | 인프라·플랫폼·기술 표준 정의 |
| **거버넌스·저장소** | 원칙·준수·예외·자산 재사용 관리 |

#### 한줄 요약
- 저장소가 원칙과 빌딩 블록을 재사용 자산으로 쌓아 두어 사업마다 같은 표준을 다시 정하고 다시 합의하는 부담을 없애고, 거버넌스는 그 표준에서 벗어나는 요구를 예외 심의 한 곳으로 모아 개별 사업의 임의 판단을 대신한다.

## Ⅳ. 흐름도

```text
[경영 전략·변화 요구]
     │
     └──────── 아키텍처 요청
                 │
                 ▼
            [EA 조직]
                 │ 1. 준비·비전 수립
                 │ 2. BA·DA·AA·TA 설계
                 │ 3. 기회·해결책 도출
                 │ 4. 이행 계획·구현 거버넌스
                 │ 5. 변경 관리·요구 갱신
                 └──────── 아키텍처 결과 반환
```

**동작 원리**

1. **준비·비전 수립**: 역량·원칙·범위·이해관계자 목표 확정
2. **BA·DA·AA·TA 설계**: As-Is·To-Be와 도메인별 갭 분석
3. **기회·해결책 도출**: 전환 대안과 빌딩 블록 조합 결정
4. **이행 계획·구현 거버넌스**: 우선순위·로드맵·준수성 통제
5. **변경 관리·요구 갱신**: 환경 변화에 따라 ADM 반복 여부 판단

#### 한줄 요약
- 비전, 도메인 설계, 해결책, 이행, 변경 관리로 ADM을 순환한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | EA | ISP | ISMP |
|:---|:---|:---|:---|
| 핵심 목적 | 전사 **구조·표준 관리** | 중장기 정보화 전략 | 단일 사업 실행 구체화 |
| 범위 | 조직 전체 자산·관계 | 전사·사업 영역 과제 | 특정 정보시스템 사업 |
| 주요 산출물 | 4대 도메인·원칙·표준 | 전략 과제·투자 로드맵 | 요구·예산·발주 자료 |
| 시간 관점 | 상시 현행화 | 중장기 계획 주기 | 사업 착수 전 상세화 |
| 연계 역할 | 구조적 기준 제공 | 투자 방향 결정 | 실행·조달 요건 확정 |

#### 한줄 요약
- EA는 구조, ISP는 전략, ISMP는 단일 사업 실행 계획을 다룬다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 |
|:---|:---|
| 부서별 시스템·라이선스 중복 | 신규 투자 전 **EA 중복성 검토** |
| 경직된 표준으로 신기술 도입 지연 | 기한·조건을 둔 **표준 예외 승인** |
| EA 문서와 운영 형상의 불일치 | 배포·자산 정보의 **자동 현행화** |
| 도메인별 모델의 추적 단절 | 전략부터 기술까지 **관계 ID 관리** |
| 구축 사업의 목표 아키텍처 이탈 | ARB 기반 **준수성 검토** |

#### 한줄 요약
- 중복 검토, 예외 승인, 현행화, 추적성, 준수성으로 EA를 운영한다.

## Ⅶ. 결론

- 전략 변화 영향이 여러 도메인에 걸리면 **EA·ADM**으로 전환 로드맵 통제

#### 한줄 요약
- 전사 영향은 4대 도메인으로 추적하고 ADM으로 우선순위 있게 전환한다.
