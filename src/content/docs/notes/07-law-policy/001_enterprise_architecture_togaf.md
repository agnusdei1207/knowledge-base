## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **전사 아키텍처(EA)**: 전략과 업무•데이터•응용•기술을 연결하는 관리 체계이다.
- **아키텍처 개발 방법(ADM)**: 비전부터 이행•변경까지 순환하는 개발 방법이다.

</details>

- 정의/개념: 전사 전략과 도메인을 정렬하고 **TOGAF 10판 ADM**으로 전환을 관리하는 체계이다.
- 배경/필요성: 부문별 구축으로 **중복 투자•데이터 불일치•표준 분산**이 발생한다.

#### 한줄 요약
- **전사 전략**에 맞춰 **네 도메인** 구조를 정렬•관리가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **업무 아키텍처(BA)**: 전략을 조직•기능•프로세스로 구체화하는 관점이다.
- **데이터 아키텍처(DA)**: 데이터 모델•흐름•소유권•표준 관점이다.
- **애플리케이션 아키텍처(AA)**: 시스템•서비스•인터페이스 책임 관점이다.
- **기술 아키텍처(TA)**: 애플리케이션 실행 기반 관점이다.
- **현행•목표•갭**: 두 구조의 차이에서 전환 과제를 도출하는 분석이다.
- **아키텍처 거버넌스**: 원칙•표준•예외•변경 승인 통제 체계이다.

</details>

- **통합 축**: BA•DA•AA•TA의 의존 관계와 변경 영향을 추적한다.
- **개발 축**: ADM 순환으로 현행•목표•갭•이행 로드맵 현행화이다.
- **통제 축**: 거버넌스로 원칙•표준•예외•변경 승인을 관리한다.

#### 한줄 요약
- 신규 시스템의 **중복•연계**와 **표준 준수**를 검토한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **업무 아키텍처(BA)**: 전략을 조직•기능•프로세스로 구체화하는 관점이다.
- **데이터 아키텍처(DA)**: 데이터 모델•흐름•소유권•표준 관점이다.
- **애플리케이션 아키텍처(AA)**: 시스템•서비스•인터페이스 책임 관점이다.
- **기술 아키텍처(TA)**: 애플리케이션 실행 기반 관점이다.

</details>

```text
                      [아키텍처 거버넌스]
                               |
          +--------------------+--------------------+
          |                    |                    |
[업무 아키텍처]      [데이터 아키텍처]      [애플리케이션 아키텍처]
          |                    |                    |
          +--------------------+--------------------+
                               |
                       [기술 아키텍처]
```

선의 의미: 아키텍처 거버넌스 아래 업무•데이터•애플리케이션•기술 도메인이 공통 원칙과 표준으로 결합되는 전사 아키텍처 계층을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 아키텍처 거버넌스 | **원칙•표준•예외•변경 승인**과 도메인 정합성 통제 |
| 업무 아키텍처 | 전략을 **조직•기능•프로세스•서비스**로 변환 |
| 데이터 아키텍처 | **데이터 모델•흐름•소유•표준** 정의 |
| 애플리케이션 아키텍처 | **시스템•서비스•인터페이스 책임** 정의 |
| 기술 아키텍처 | **서버•네트워크•보안•클라우드 기반** 정의 |

#### 한줄 요약
- **네 도메인**을 구분하고 **거버넌스**로 원칙•변경을 통제한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **ADM 재순환**: 구현 결과를 반영해 갭 분석으로 돌아가는 절차이다.

</details>

```text
경영진
   │ 전략•비전•범위 전달
   ▼
아키텍처팀
   │ 1. 현행•목표•갭 모델 수립
   ▼
사업포트폴리오
   │ 2. 전환 로드맵•투자안 제출
   ▼
거버넌스위원회
   │ 3. 준수•예외 결정 반환
   ▼
사업포트폴리오
   │ 4. 구현 결과•변경 요구 회신
   │    (ADM 재순환)
   ▼
아키텍처팀
   │ EA 현행화•투자 결과
   ▼
경영진
```

**동작 원리**

1. **현행•목표•갭 모델 수립**: 도메인별 중복•단절•표준 차이를 식별한다.
2. **전환 로드맵•투자안 제출**: 과제•선행 관계•비용•효과를 구성한다.
3. **준수•예외 결정 반환**: 목표 구조와 원칙의 보완 조건을 승인한다.
4. **구현 결과•변경 요구 회신**: 저장소에 반영해 ADM을 재순환한다.

#### 한줄 요약
- **현행•목표 갭**으로 로드맵을 만들고 **결과 재반영**이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **정보화 계획 체계**: 구조•투자•발주 계획의 역할을 구분한다.
- **정보전략계획(ISP)**: 중장기 정보화 과제와 투자 로드맵이다.
- **정보시스템 마스터플랜(ISMP)**: 개별 사업의 요구•규모•예산 구체화이다.

</details>

| 정보화 계획 체계 | EA | ISP | ISMP |
|:---|:---|:---|:---|
| 적용 기준 | **전사 구조•표준** 통제 | **중장기 투자 계획** 수립 | **개별 사업 발주** 상세화 |
| 핵심 특징 | **구조•변경 거버넌스** | **과제•투자 로드맵** | **요구•규모•예산** 구체화 |
| 한계 | **지속 현행화 비용** | **발주 상세 부족** | **전사 전략 관점 부족** |

> 요약: **EA**는 구조, **ISP•ISMP**는 투자•발주를 정의한다.

#### 한줄 요약
- **EA**는 구조, **ISP•ISMP**는 투자•발주 규격을 정의한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **현행 정보 불일치**: 시스템 변경이 EA 저장소에서 누락된 상태이다.
- **범정부 EA 저장소**: 공공 정보자원•아키텍처 공동 관리소이다.
- **공통 식별자**: 도메인 간 동일 자원을 연결하는 기준값이다.
- **종단 영향 분석**: 변경 영향을 연계 도메인 전체에서 분석한다.
- **거버넌스 경직**: 표준•승인 강제로 변화 대응이 느린 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템 변경이 빠져 생기는 **현행 정보 불일치** | 승인•배포•폐기와 **범정부 EA 저장소** 갱신 연결 | 투자 검토의 **현행성** 확보 |
| 도메인 관계가 끊겨 생기는 **변경 영향 추적 불가** | 전 도메인을 **공통 식별자**로 연결 | 전략 변화의 **종단 영향 분석** |
| 표준만 강제해 생기는 **거버넌스 경직** | **예외 기간•보완 통제•종료 조건** 승인 | 정합성과 **사업 민첩성** 균형 |

#### 한줄 요약
- **범정부 EA**로 **공동 활용•중복 투자** 대상을 검토한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **TOGAF ADM 로드맵**: 갭 과제를 선행 관계•투자 순서로 배치한다.

</details>

- 전사 구조 통제는 **EA**, 갭 이행은 **ADM 로드맵**을 적용한다.

#### 한줄 요약
- 변화 결과를 **현행화**해 **전사 구조 일관성**을 유지한다.
