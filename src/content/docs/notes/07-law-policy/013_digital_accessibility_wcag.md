## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디지털 접근성(Digital Accessibility / W3C WAI & 지능정보화기본법 제46조)**: 장애인(시각, 청각, 지체, 뇌병변 등), 고령자, 일시적 신체 제약이 있는 사용자를 포함한 모든 사람이 어떠한 환경이나 디바이스(PC, 모바일, 키오스크)에서도 웹 사이트, 모바일 앱, 디지털 미디어의 정보와 기능을 동등하게 인식하고, 조작하며, 이해할 수 있도록 보장하고, 화면 낭독기(스크린 리더) 등 보조공학 기기(Assistive Technology)와의 호환성을 완전무결하게 제공하는 설계 원칙.
- **시각/마우스 편향 인터페이스에 따른 정보 소외 결함(Mouse/Visual Bias Defect)**: 이미지 버튼에 대체 텍스트(`alt`)가 없어 시각장애인이 결제 버튼을 누를 수 없거나, 마우스 클릭 이벤트만 구현하여 키보드 탭(Tab) 키 이동이 불가능하고, 팝업 레이어가 화면 낭독기의 초점(Focus)을 가두어 버리는 '키보드 트랩(Keyboard Trap)'으로 인해 장애인이 행정·금융 서비스 이용에서 완전히 차단되는 구조적 결함.

</details>

- 정의/개념: 모든 사람의 보편적 정보 접근권을 실현하기 위해 **W3C WCAG 2.2 및 KWCAG 2.2 표준 준거 $\rightarrow$ POUR 4대 원칙(인식성$\cdot$운용성$\cdot$이해성$\cdot$견고성) 설계 $\rightarrow$ WAI-ARIA 1.2 동적 속성 부여 $\rightarrow$ 3단계 다중 검증(자동화 스캔$\cdot$전문가 수동 실사$\cdot$장애인 당사자 사용자 테스트) $\rightarrow$ 웹 접근성 품질마크 인증 획득** 을 집행하는 **디지털 포용 엔지니어링 체계**
- 배경/필요성: 장애인차별금지법 제21조(정보통신·의사소통 등에서의 정당한 편의제공의무) 및 공공기관 웹/앱 접근성 준수 의무화에 따라, 법적 처벌 방지 및 사회적 책임(ESG) 완수를 위한 필수 품질 속성으로 정착

#### 한줄 요약
- 디지털 접근성은 POUR 4대 원칙과 WCAG 2.2 지침을 통해 장애인과 고령자를 포함한 모든 사용자의 동등한 웹/앱 이용을 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **WCAG 2.2 4대 핵심 POUR 원칙**:
  - **1. 인식성 (Perceivable)**: 정보와 UI 컴포넌트는 사용자가 감각(시각/청각)으로 인지할 수 있어야 함 (대체 텍스트, 4.5:1 명도 대비, 자막).
  - **2. 운용성 (Operable)**: UI 컴포넌트와 내비게이션은 사용자가 직접 조작할 수 있어야 함 (키보드 완결, 충분한 시간, 초점 이동).
  - **3. 이해성 (Understandable)**: 정보와 UI 조작법은 명확하고 예측 가능해야 함 (기본 언어 명시, 에러 식별 및 정정 제안).
  - **4. 견고성 (Robust)**: 다양한 사용자 에이전트(브라우저, 스크린 리더)에서 해석 가능해야 함 (표준 마크업, WAI-ARIA).

</details>

- **3단계 적합성 등급(A / AA / AAA Conformance)**: 법적 최소 표준인 Level A부터 글로벌 공공/기업의 표준 준거점인 **Level AA(권고)**, 최고 수준의 접근성을 보장하는 Level AAA로 체계화
- **WAI-ARIA(Accessible Rich Internet Applications) 1.2 지원**: SPA(Single Page Application)와 React/Vue의 동적 컴포넌트(모달, 드롭다운, 아코디언)에 `role`, `aria-expanded`, `aria-live` 속성을 부여하여 스크린 리더에 실시간 상태 전달
- **다중 삼각 검증 체계(Triangulated Testing)**: 자동화 정적 분석 도구(Lighthouse, axe-core)의 한계(탐지율 40%)를 극복하기 위해, 전문가 키보드 전수 실사와 시각/지체 장애인 당사자 사용자 평가(UAT)를 병행

#### 한줄 요약
- POUR 4대 원칙, Level AA 글로벌 표준, WAI-ARIA 동적 접근성, 3단계 다중 검증(자동+수동+당사자)을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **디지털 접근성 핵심 엔지니어링 4대 영역**:
  1. **시각/청각 대체 계층 (Perceivable)**: `alt` 속성, 멀티미디어 자막, 4.5:1 텍스트 명도 대비, 200% 텍스트 확대.
  2. **키보드 및 내비게이션 계층 (Operable)**: 키보드 트랩 방지, 논리적 `tabindex` 순서, 건너뛰기 링크(Skip Navigation).
  3. **콘텐츠 가독성 및 오류 방지 계층 (Understandable)**: HTML `lang="ko"` 속성, 폼 입력 오류 메시지 및 정정 안내.
  4. **시맨틱 마크업 및 보조기술 연동 계층 (Robust)**: HTML5 Semantic 태그(`<main>`, `<nav>`), WAI-ARIA 1.2.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. W3C WCAG 2.2 POUR 4대 원칙 및 핵심 기술 지침 아키텍처 ]            │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 1. 인식성 (Perceivable) ]       │ [ 2. 운용성 (Operable) ]            │
│ ├─ 이미지 대체 텍스트 (`alt="..."`)├─ 마우스 없이 키보드(Tab) 100% 조작  │
│ ├─ 명도 대비 4.5:1 이상 (텍스트)  ├─ 키보드 트랩(Trap) 0건 방어        │
│ └─ 동영상 캡션/수어 통역 자막 제공 └─ 본문 바로가기 건너뛰기 링크 제공   │
├───────────────────────────────────┼─────────────────────────────────────┤
│ [ 3. 이해성 (Understandable) ]    │ [ 4. 견고성 (Robust) ]              │
│ ├─ 페이지 기본 언어 `<html lang="ko">` ├─ HTML5 표준 시맨틱 태그 구조화    │
│ ├─ 폼 입력 오류 시 명확한 수정 안내├─ WAI-ARIA 1.2 역할/상태 실시간 전파 │
│ └─ 일관된 내비게이션 및 포커스    └─ [스크린 리더(NVDA, 보이스오버) 호환]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 4대 원칙(POUR)의 엔지니어링 세부 지침이 유기적으로 결합되어 스크린 리더와 키보드 사용자에게 완전한 접근성을 보장하는 구조

| POUR 원칙 | 핵심 WCAG 2.2 성공 기준 (Level AA) | 주요 구현 기술 및 속성 | 검증 방법 |
|:---|:---|:---|:---|
| **1. 인식성** | 1.1.1 비텍스트 콘텐츠 대체 텍스트<br>1.4.3 최소 명도 대비 (4.5:1) | `<img>`의 `alt` 속성,<br>CSS `color` 및 `background-color` | 자동 스캔 + 화면 낭독기 청취 |
| **2. 운용성** | 2.1.1 키보드 접근성<br>2.1.2 키보드 트랩 방지 | 논리적 포커스 순서,<br>`<a href="#content">` 본문 건너뛰기 | **키보드 Tab / Shift+Tab 단독 실사** |
| **3. 이해성** | 3.1.1 페이지 기본 언어<br>3.3.1 오류 식별 및 설명 | `<html lang="ko">`,<br>`aria-describedby="error-msg"` | 폼 유효성 검증 오류 테스트 |
| **4. 견고성** | 4.1.2 이름, 역할, 값 (Name, Role, Value)<br>4.1.3 상태 메시지 | `role="dialog"`, `aria-modal="true"`,<br>`aria-live="polite"` | **스크린 리더(NVDA/VoiceOver) 실측**|

#### 한줄 요약
- 인식성(대체텍스트/명도대비), 운용성(키보드완결), 이해성(언어/에러안내), 견고성(WAI-ARIA)의 4대 축으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **디지털 접근성 개발 및 품질 인증 5단계 프로세스**:
  1. 기획 및 디자인 단계에서 컬러 팔레트 4.5:1 명도 대비 및 건너뛰기 링크 레이아웃 설계
  2. 프론트엔드 퍼블리싱 시 HTML5 시맨틱 태그 및 WAI-ARIA 1.2 접근성 마크업 구현
  3. axe-core 및 Lighthouse 자동화 도구로 정적 마크업 오류 선제 수정
  4. 마우스를 뽑고 키보드만으로 모든 폼 입력과 팝업 닫기가 가능한지 전문가 수동 실사
  5. 시각/지체 장애인 평가단이 스크린 리더로 실제 민원 신청 과업을 수행하여 최종 인증 마크 획득

</details>

```text
1. [기획/디자인: 접근성 요구사항 정의 (Design)]
    ├─ 컬러 가이드라인 수립: 텍스트와 배경 간 명도 대비 4.5:1 이상 확정 (Figma 플러그인 검증)
    └─ [포커스 링(Focus Ring) 시각적 표시 설계 및 폼 레이블 명확화]
            │
            ▼
2. [개발/구현: 시맨틱 마크업 및 WAI-ARIA 적용]
    ├─ `<button>`, `<nav>`, `<main>` 등 표준 시맨틱 태그 사용 (의미 없는 `<div>` 남용 금지)
    ├─ 이미지에 구체적 의미가 담긴 `alt="2027년 국가장학금 신청 기간 안내 포스터"` 작성
    └─ [모달 팝업 오픈 시 `aria-modal="true"` 적용 및 포커스를 팝업 내부로 자동 이동]
            │
            ▼
3. [1차 자동화 정적 스캔 (Automated Scan)]
    ├─ CI 파이프라인에서 axe-core 및 Pa11y 스크립트 실행
    └─ [누락된 `alt` 태그 5건 및 명도 대비 미달 2건 적발 ➔ 즉각 수정 완료 (결함 0건)]
            │
            ▼
4. [2차 전문가 키보드 수동 실사 (Manual Audit)]
    ├─ 마우스 사용 전면 금지 ➔ Tab, Enter, Space 키만으로 전 메뉴 탐색
    ├─ [지적]: 커스텀 드롭다운 메뉴가 키보드 Enter 키로 열리지 않는 결함 적발
    └─ [수정]: `onKeyDown` 이벤트 핸들러에 Enter/Space 키 바인딩 추가 (Pass)
            │
            ▼
5. [3차 장애인 사용자 실증 시험 (User Testing)]
    ├─ 전맹 시각장애인 평가원이 NVDA 스크린 리더로 로그인부터 결제까지 전 과정 수행
    ├─ 모든 동적 상태 변화(로딩 중, 에러 발생)가 음성으로 100% 정상 전달 확인
    └─ [한국웹접근성평가원 공인 '웹 접근성 품질인증 마크(WA 마크)' 최종 획득]
```

**동작 원리**

1. **시맨틱 태그의 구조적 해석**: 브라우저가 화면을 렌더링할 때 보조기술을 위한 접근성 트리(Accessibility Tree)를 생성하는데, 시맨틱 태그(`<button>`, `<input>`)를 사용해야만 스크린 리더가 "버튼", "입력창"으로 인식
2. **논리적 초점 순서(Logical Focus Order)**: CSS `float`나 `flex-reverse`로 시각적 순서를 뒤바꾸더라도, DOM의 실제 마크업 순서가 논리적으로 작성되어 있어야 키보드 Tab 키 이동 시 시선과 일치
3. **WAI-ARIA의 상태 알림(aria-live)**: 화면이 새로고침되지 않고 AJAX로 결제 완료 메시지가 떴을 때, `aria-live="polite"` 속성이 있어야 스크린 리더가 현재 읽던 내용을 마친 후 변경된 결과를 음성으로 낭독
4. **키보드 트랩(Keyboard Trap)의 완전 격리**: 모달 팝업이 떴을 때 Tab 키를 계속 누르면 팝업 바깥의 보이지 않는 배경 요소로 초점이 빠져나가지 않도록 팝업 내부에서 초점이 순환(Focus Trapping)되도록 구현
5. **자동화 검사의 한계 극복**: 자동화 툴은 `alt` 속성의 존재 유무(True/False)만 알 뿐, `alt="이미지1"`처럼 무의미한 텍스트가 들어간 것은 판별할 수 없으므로 사람의 청취 검사 필수

#### 한줄 요약
- 디자인 명도 대비, 시맨틱 WAI-ARIA 마크업, 자동화 스캔, 전문가 키보드 실사, 장애인 사용자 실증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **접근성 표준 발전 단계 비교**:
  - WCAG 2.0 (2008): 데스크톱 웹 중심 4대 원칙 61개 성공 기준.
  - WCAG 2.1 (2018): 모바일 터치, 저시력자, 인지 장애 성공 기준 추가 (17개 신설).
  - WCAG 2.2 (2023): 최신 개정판, 터치 타깃 크기, 포커스 가림 방지, 중복 입력 방지 추가 (9개 신설).

</details>

| 비교 항목 | WCAG 2.0 (레거시) | WCAG 2.1 (모바일 확장) | WCAG 2.2 (최신 표준) |
|:---|:---|:---|:---|
| **중점 적용 환경** | **데스크톱 PC 웹 환경 중심** | **스마트폰 모바일 웹/앱, 터치스크린**| **모바일 고도화, 키오스크, 인지 접근성**|
| **핵심 신설 기준** | POUR 4대 원칙 61개 기준 확립 | 화면 방향(세로/가로), 텍스트 간격, 포인터 제스처 | **초점 가림 방지, 터치 타깃($24\times24\text{px}$), 중복입력 방지**|
| **저시력/모바일 배려**| 단순 확대 위주 | 확대 시 가로 스크롤 없는 리플로우(Reflow)| 클릭 영역 크기 강제, 드래그 동작 대안 |
| **적합성 평가 기준** | Level A, AA, AAA 3단계 | Level A, AA, AAA 3단계 | **Level A, AA, AAA (글로벌 공인 표준)**|
| **국내 표준 연계** | KWCAG 2.0 | KWCAG 2.1 국가 표준 | **최신 KWCAG 2.2 개정 반영 기준** |

#### 한줄 요약
- WCAG 2.0은 데스크톱 웹, 2.1은 모바일/터치, 2.2는 터치 타깃 및 포커스 가림 방지 등 사용자 경험 고도화이다.

<details><summary>용어 설명</summary>

- **디지털 접근성 실무 구현 시 3대 위험 요소와 엔지니어링 대책**:

|:---|:---|:---|

#### 한줄 요약
- 3단계 다중 검증으로 결함을 잡고, 디자인 시스템 내재화로 재작업을 막으며, CI/CD 자동화로 회귀를 방어한다.

## Ⅶ. 결론

- 장애 유무나 연령, 디바이스의 제약 없이 모든 국민이 디지털 사회의 정보와 혜택을 차별 없이 누리도록 보장하는 가장 숭고한 기술적 인권 규범인 **디지털 접근성과 WCAG 2.2 체계**는 단순한 법적 규제 준수를 넘어 사용자 경험(UX)의 완성도와 비즈니스 포용성을 결정짓는 최상위 소프트웨어 공학 표준이며, 실무 구현 시 **POUR 4대 원칙의 철저한 준수**, **Level AA 적합성 기준에 따른 WAI-ARIA 1.2의 정밀 구현**, **자동화 툴과 장애인 당사자 실측의 다중 삼각 검증**, **CI/CD 파이프라인을 통한 접근성 회귀 방지**를 완성하여 최고 수준의 디지털 포용성과 무결점 유니버설 디자인을 완성

#### 한줄 요약
- POUR 4대 원칙과 WAI-ARIA 및 다중 실측 검증을 통해 차별 없는 디지털 접근성을 완성한다.
