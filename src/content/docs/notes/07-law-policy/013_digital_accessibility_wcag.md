## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **디지털 접근성**: 조건과 무관한 정보 인식•운용•이해•호환성이다.
- **보조기술**: 장애 사용자의 정보 인식•기능 조작 지원 기술이다.
- **보조기술 호환 보장**: 웹 구조•상태•기능을 보조기술이 정확히 해석하게 하는 원칙이다.

</details>

- 정의/개념: **디지털 접근성**은 장애•연령•기기와 무관하게 디지털 정보와 기능을 인식•운용•이해하고 보조기술과 호환되게 보장하는 설계 원칙이다.
- 배경/필요성: 시각•마우스 중심 인터페이스의 제약을 **보조기술 호환 보장**으로 해소한다.


#### 한줄 요약
- 키보드•화면 낭독기로 정보•기능을 동등하게 이용하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **POUR 원칙**: 인식•운용•이해•견고성의 네 접근성 원칙이다.
- **A•AA•AAA 적합성 수준**: 성공 기준의 기본•중간•최고 등급이다.
- **다중 검증**: 자동•수동•보조기술 사용자 시험을 결합하는 검증 방식이다.

</details>

- **POUR 원칙**으로 접근성을 제품 품질의 필수 속성으로 관리한다.
- **A•AA•AAA 적합성 수준**으로 성공 기준을 분류한다.
- **다중 검증**: 자동 진단•수동 점검•보조기술 사용자 시험을 결합하여 실제 접근 장벽을 확인한다.

#### 한줄 요약
- 화면 낭독기 해석과 키보드 조작 가능성을 확인한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **웹 콘텐츠 접근성 지침(WCAG)**: 인식•운용•이해•호환 성공 기준이다.
- **사용자 인터페이스(UI)**: 정보 인식과 기능 조작의 화면•입력 접점이다.
- **WAI-ARIA**: 동적 UI 역할•상태•속성의 보조기술 전달 명세이다.
- **접근성 회귀**: 변경 뒤 키보드•대체 텍스트•낭독기 동작 재결함이다.

</details>

```text
                        [운영관리]
                       /          \
               [요구사항]       [테스트]
                   |               |
               [UI 구현]-----[보조기술]
```

선의 의미: 운영관리는 요구사항과 테스트 기준을 함께 유지하고, UI 구현은 요구사항을 반영해 보조기술과 호환되며, 테스트는 그 호환성을 검증한다.

| 구성요소 | 책임 |
|:---|:---|
| 요구사항 | **WCAG** 성공 기준 반영 |
| UI 구현 | **UI**에 **WAI-ARIA** 역할•상태 구현 |
| 보조기술 | 화면낭독기•대체입력 호환성 확보 |
| 테스트 | 자동•수동•사용자 검증 |
| 운영관리 | 변경 시 **접근성 회귀** 검토 |

#### 한줄 요약
- POUR 설계와 보조기술 사용자 시험을 결합한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **대체 텍스트**: 시각 정보의 의미•기능을 문자로 전달하는 수단이다.
- **키보드 초점 순서**: 입력•버튼•링크로 이동하는 논리적 순서이다.
- **접근성 회귀 시험**: 변경 뒤 접근성 결함의 재발을 확인하는 시험이다.
- **사용자 장벽•성공 기준 정의**: 과업별 접근 장벽을 WCAG 성공 기준에 연결하는 단계이다.
- **의미 구조•대체 수단 구현**: 표준 마크업•키보드•대체 텍스트를 적용하는 단계이다.
- **키보드•보조기술 시험**: 초점 순서와 화면 낭독기 해석을 확인하는 단계이다.
- **접근성 결함 개선 요청**: 과업 영향에 따라 결함의 수정 우선순위를 정하는 단계이다.

</details>

```text
접근성 담당
   │ 1. 사용자 장벽•성공 기준 정의
   ▼
개발자
   │ 2. 의미 구조•대체 수단 구현
   ▼
사용자
   │ 3. 키보드•보조기술 시험
   ▼
접근성 담당
   │ 4. 접근성 결함 개선 요청
   │    (접근성 결함 해소까지 순환)
   ▼
개발자
   │ 5. 접근성 회귀 시험
   ▼
사용자
   │ 접근 가능한 버전 제공
   ▼
```

### 동작 원리

1. **사용자 장벽•성공 기준 정의**: 과업별 장벽을 WCAG 기준에 연결한다.
2. **의미 구조•대체 수단 구현**: **대체 텍스트**를 적용한다.
3. **키보드•보조기술 시험**: **키보드 초점 순서**를 확인한다.
4. **접근성 결함 개선 요청**: 과업 영향 기반 우선순위를 결정한다.
5. **접근성 회귀 시험**: 공통 구성요소의 결함 재발을 확인한다.

#### 한줄 요약
- **대체 텍스트** 제공 후 화면 낭독기 해석을 시험한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **견고성**: 표준 마크업으로 브라우저•보조기술 호환성을 확보하는 성질이다.

</details>

| 구분 | 인식성 | 운용성 | 이해성 | 견고성 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 시각•청각 대체 수단 | 입력 도구•시간 통제 | 문맥 이해•입력 오류 예방 | **견고성** 확보 |
| 핵심 특징 | 대체 정보•명도 대비 | 키보드•시간 조작 | 가독성•오류 방지 | 표준 마크업•호환성 |
| 한계 | 대체 정보 품질 편차 | 복합 제스처 대체 곤란 | 쉬운 표현 기준 편차 | 보조기술별 해석 차이 |

> 요약: **POUR**는 인식•운용•이해•견고성의 성공 기준이다.

#### 한줄 요약
- 인식•운용•이해와 **견고성**의 접근 장벽을 비교한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **사용자 시험**: 장애 사용자의 실제 과업으로 이용 장벽을 확인하는 시험이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 자동 검사만으로 적합성 판단 | 자동•수동•보조기술•**사용자 시험** 병행 | 실제 장벽 탐지율 향상 |
| 디자인 이후 접근성 보완 | 개발 완료 기준에 WCAG 성공 기준 반영 | 재작업 감소 |
| 기능 변경 후 **접근성 회귀** | 공통 구성요소 **접근성 회귀 시험** | 지속 적합성 유지 |

#### 한줄 요약
- 전자 신고는 고대비와 입력•초점 순서 일치를 보장한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **WCAG 2.2 AA**: A•AA 성공 기준을 충족하는 중간 수준이다.

</details>

- 공공•필수 서비스는 **WCAG 2.2 AA**와 보조기술 시험을 병행한다.

#### 한줄 요약
- 기능 변경마다 자동 검사와 보조기술 시험을 반복한다.
