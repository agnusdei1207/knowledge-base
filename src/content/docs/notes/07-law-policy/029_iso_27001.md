## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ISO/IEC 27001**: 인증 가능한 정보보안경영시스템 요구사항.
- **정보보안경영시스템(Information Security Management System, ISMS)**: 위험·통제의 운영·평가·개선 체계.

</details>

- 정의: **정보보안경영시스템**의 수립·운영·개선을 인증하는 **ISO/IEC 27001**
- 배경/필요성: 통제 목록만으로는 **업무 위험·성과**와 경영진 책임 연결 곤란

#### 한줄 요약

- **정보보안경영시스템** 기반 보안 위험과 통제를 운영•개선한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상황 기반성**: 내•외부 이슈와 이해관계자 요구로 범위•방침•목표를 결정하는 특성.
- **위험 기반성**: 일관된 위험평가•처리 방법으로 업무 위험에 맞는 통제를 선택하는 특성.
- **지속 개선성**: 성과지표•내부감사•경영검토•시정조치로 경영체계와 통제 효과를 반복 개선하는 특성.
- **적용성 선언서(SoA)**: 통제 선택•제외 근거와 구현 상태를 기록한 문서.

</details>

- **상황 기반성**: 조직 이슈·이해관계자별 범위·방침·목표 설정
- **위험 기반성**: 위험평가와 SoA 기반 통제 선택·제외
- **지속 개선성**: 성과·감사·경영검토·시정조치 순환

#### 한줄 요약

- 위험에 맞춰 통제를 선택하고 적용·제외 근거를 기록한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **부속서 A**: 정보보안 위험처리에 필요한 통제를 선택할 때 참조하는 목록.
- **위험처리계획**: 처리 옵션•책임•통제•일정•잔여위험을 연결한 계획.
- **ISMS 범위**: 조직•업무•정보•시설•기술•의존성의 경계.
- **리더십**: 경영진이 보안 책임과 자원을 승인하는 경영 요소.
- **방침**: 조직의 정보보안 방향과 원칙을 선언한 기준.
- **목표**: 정보보안 성과를 측정할 수 있게 정한 달성 기준.
- **성과평가**: 통제 지표와 객관적 증거로 ISMS 효과를 확인하는 활동.
- **내부감사**: ISMS 요구사항 준수 여부를 독립적으로 확인하는 활동.
- **경영검토**: 경영진이 성과•변화•부적합을 검토하는 활동.
- **시정조치**: 부적합의 원인을 제거해 재발을 막는 활동.
- **개선**: 경영체계와 통제의 효과를 지속해서 높이는 활동.

</details>

```text
                    [조직 상황•ISMS 범위]
                       /             \
          [리더십•방침•목표]   [위험평가•처리•SoA]
                       \             /
                   [통제 운영•성과평가]
                              |
                   [경영검토•시정•개선]
```

선의 의미: 조직 상황•ISMS 범위가 리더십과 위험평가의 경계를 정하고, 두 요소는 통제 운영•성과평가를 지배하며, 경영검토•시정•개선은 그 효과를 감독한다.

| 구성요소 | 책임 |
|:---|:---|
| 조직 상황•ISMS 범위 | 업무·법규·의존 관계를 반영한 **ISMS 범위** 정의 |
| 리더십•방침•목표 | 경영진의 자원 지원과 **방침·목표** 승인 |
| 위험평가•처리•SoA | **위험처리계획**·**부속서 A**에 따른 통제 근거 문서화 |
| 통제 운영•성과평가 | **성과평가**·**내부감사**에 따른 통제 효과 확인 |
| 경영검토•시정•개선 | **경영검토** 후 **시정조치·개선** 결정 |

#### 한줄 요약

- **ISMS 범위** 및 **위험처리계획** 정하고 통제 효과를 순환 개선한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **계획-실행-점검-개선(PDCA)**: 통제 성과를 점검•개선하는 순환.
- **조직 상황•범위 승인 요청**: 업무•정보•시설•공급자 경계를 경영진에게 제시하는 단계.
- **방침•위험 기준•자원 승인**: 경영진이 위험 수용 기준•역할•예산•역량•목표를 확정하는 단계.
- **위험처리계획•SoA 제출**: 위험별 처리 옵션과 통제의 선택•제외•구현 상태를 연결하는 단계.
- **통제 성과•내부감사 보고**: 지표•사고•준수•감사 결과로 계획 대비 효과를 평가하는 단계.
- **시정조치•개선 결정**: 부적합 원인을 제거하고 변화한 위험을 다음 계획에 반영하는 단계.
</details>

```text
보안조직
   │ 1. 조직 상황•범위 승인 요청
   ▼
경영진
   │ 2. 방침•위험 기준•자원 승인
   ▼
보안조직
   │ 3. 위험처리계획•SoA 제출
   │ 4. 통제 성과•내부감사 보고
   ▼
경영진
   │ 5. 시정조치•개선 결정
   ▼
보안조직
```

### 동작 원리

1. 조직 상황•범위 승인 요청: 업무·정보·시설·공급자의 **ISMS 경계** 제시
2. 방침•위험 기준•자원 승인: **위험 수용 기준**·역할·예산·목표 승인
3. 위험처리계획•SoA 제출: 위험별 통제 선택·제외의 **SoA 근거** 제출
4. 통제 성과•내부감사 보고: 지표·사고·준수·감사의 **통제 효과** 보고
5. 시정조치•개선 결정: **PDCA**에 따른 부적합 원인과 변화 위험 반영

#### 한줄 요약

- **조직 상황•범위 승인 요청**부터 **시정조치•개선 결정**까지 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ISO/IEC 27002**: 정보보안 통제를 선택•구현•운영할 때 참고하는 상세 지침.

</details>

| 구분 | ISO/IEC 27001:2022 | ISO/IEC 27002 |
|:---|:---|:---|
| 적용 기준 | **ISO/IEC 27001**의 ISMS 인증 요구사항 | **ISO/IEC 27002**의 통제 구현 지침 |
| 핵심 특징 | 인증 가능한 **경영시스템 요구사항** | **통제 목적**과 구현 지침 |
| 한계 | **형식적 문서화**와 통제 미이행 가능성 | **인증 요구사항**으로 오인 가능 |

#### 한줄 요약

- **ISO/IEC 27001** 인증 요구사항, **ISO/IEC 27002** 기반 통제 구현 지침이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인증 범위의 의도적 축소**: 핵심 업무나 공급자 의존성을 인증 경계에서 제외해 실제 위험이 관리체계 밖에 남는 문제.
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인증 범위의 의도적 축소 | 핵심 업무·공급자 의존성을 포함한 **ISMS 범위** 검증 | 실질 위험을 포괄하는 **인증 경계** 확보 |
| 부속서 A 통제의 점검표 적용 | **적용성 선언서**에 통제 선택·제외 근거 기록 | 위험과 통제의 **추적성** 향상 |
| 문서와 실제 운영의 괴리 | 표본 증거와 효과 지표의 **내부감사** 확인 | **통제 실효성** 입증 |

#### 한줄 요약

- 변경 승인 기록과 감사 로그로 **성과평가** 객관적 증거를 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **인증 판단 기준(Certification Criteria)**: 요구사항·SoA·운영 증거의 위험 정합성 기준.

</details>

- 인증 목적은 **ISO/IEC 27001**, 통제 구현은 **ISO/IEC 27002** 선택

#### 한줄 요약

- 통제 선택 근거와 운영 증거가 위험평가에 맞는지 확인한다.
