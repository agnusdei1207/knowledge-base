## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디지털 플랫폼 정부**: 공공 데이터·서비스와 민간 역량을 연결하는 수요자 중심 정부 모델.
- **Once-Only 원칙**: 정부가 보유한 정보를 국민에게 다시 제출하게 하지 않는 원칙.

</details>

- 정의/개념: 공공 데이터·서비스를 민관 플랫폼으로 연결하는 **수요자 중심 정부**
- 배경/필요성: 기존 전자정부(e-Government) 시스템이 행정기관별 사일로화된 온라인 서비스 제공에 머물러 있어, 국민과 기업이 동일한 증명 서류를 기관마다 반복 발급·제출해야 하고 민간 혁신 서비스와의 연계가 단절되어 국민 체감 서비스 만족도가 저하되는 구조적 한계가 발생함에 따라, 공공 데이터와 서비스를 오픈 API 기반의 DPG 허브(DPG Hub)로 통합하고 민간 플랫폼과 결합하는 디지털 플랫폼 정부(DPG) 체계를 도입하여 **정부 보유 행정정보의 재요구를 금지하는 '단 한 번 제출 원칙(Once-Only Principle)', 공공 마이데이터 및 모바일 신분증(DID) 기반의 선제적·맞춤형 원스톱 행정 서비스 실현 및 제로 트러스트 보안 거버넌스 확보**를 달성할 필요

#### 한줄 요약
- DPG는 공공 데이터와 민간 서비스를 연결해 국민 중심 행정을 제공한다.

## Ⅱ. 특징

- 자격과 상황에 맞게 제공하는 **선제적 맞춤 서비스**
- 이미 보유한 정보를 재요구하지 않는 **Once-Only**
- 정보주체가 전송을 통제하는 **공공 마이데이터**
- 민간 앱에서 공공 서비스를 쓰는 **오픈 API·GovTech**
- 기관 데이터를 연결하는 **DPG 허브**
- 매 요청을 검증하는 **제로 트러스트 보안**

#### 한줄 요약
- 선제 서비스, Once-Only, 마이데이터, 민관 API, 제로 트러스트가 핵심이다.

## Ⅲ. 구조 및 구성요소

```text
┌──────────── 디지털 플랫폼 정부 ────────────┐
│                                           │
├── [국민·기업 채널]                        │
│   ├── 공공 포털                           │
│   └── 민간 플랫폼                         │
├── [DPG 허브·오픈 API]                     │
│   ├── 공공 마이데이터                     │
│   └── 통합 신원·동의                      │
└── [기관 데이터·서비스]                    │
    └── [제로 트러스트·감사]                │
```

| 구성요소 | 책임 |
|:---|:---|
| **국민·기업 채널** | 공공·민간 접점의 통합 서비스 제공 |
| **DPG 허브·오픈 API** | 기관·민간 데이터와 서비스 중계 |
| **공공 마이데이터** | 본인정보 조회·전송 동의 통제 |
| **통합 신원·동의** | 인증·인가·목적별 동의 관리 |
| **제로 트러스트·감사** | 연속 검증과 접근 이력 추적 |

#### 한줄 요약
- 허브가 채널과 기관 데이터 사이에 끼어들어 중계를 맡으므로 기관마다 따로 연계를 협의하고 규격을 맞추던 반복이 사라지고, 신원·동의 계층이 그 중계 앞에서 목적별 동의를 확인해 데이터가 오갈 근거를 먼저 세운다.

## Ⅳ. 흐름도

```text
[국민]
     │
     └──────── 서비스 요청·동의
                 │
                 ▼
            [민간·공공 채널]
                 │ 1. 신원·동의 검증
                 ▼
              [DPG 허브]
                 │ 2. 자격 데이터 조회
                 │ 3. 맞춤 서비스 판정
                 │ 4. Once-Only 신청 전달
                 ▼
            [처리 행정기관]
                 │ 5. 결과·이력 제공
                 └──────── 처리 결과 반환
```

**동작 원리**

1. **신원·동의 검증**: 목적·범위·기간별 인증과 정보 제공 동의 확인
2. **자격 데이터 조회**: 기관 API로 필요한 정보만 최소 조회
3. **맞춤 서비스 판정**: 정책 규칙과 데이터로 대상 서비스 식별
4. **Once-Only 신청 전달**: 기존 보유 정보로 신청·검증 자료 구성
5. **결과·이력 제공**: 처리 상태와 데이터 접근·전송 기록 제공

#### 한줄 요약
- 흐름의 비용은 자격 데이터를 누가 모으느냐에서 갈려, 국민이 구비서류로 자격을 증명하던 부담을 허브의 기관 간 최소 조회로 옮긴 대가로 목적별 동의 검증과 데이터 접근 이력 제공이 새로 붙는다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 전자정부 | 디지털 플랫폼 정부 |
|:---|:---|:---|
| 서비스 관점 | 기관·공급자 중심 | **국민·기업 수요 중심** |
| 제공 방식 | 기관별 온라인 신청 | 선제 안내·통합 신청 |
| 서류 처리 | 증명서 발급·재제출 | **Once-Only 정보 재사용** |
| 민간 관계 | 공공 포털 중심 | 오픈 API·민간 채널 협력 |
| 데이터 활용 | 기관별 보유·연계 | 허브 기반 목적별 연계 |
| 보안 관점 | 경계·망 중심 | 데이터·신원·연속 검증 중심 |

#### 한줄 요약
- 전자정부는 절차 온라인화, DPG는 데이터 기반 민관 통합에 초점을 둔다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별 코드·메타데이터 불일치 | 공통 표준·MDM 기반 **상호운용성** | 기관 간 데이터 호환 |
| 개인정보의 목적 외 이용 | 최소 수집·목적별 **동의·전송 통제** | 프라이버시 보호 |
| 민간 채널 장애의 행정 전파 | 서킷 브레이커·대체 채널 **복원력** | 서비스 연속성 확보 |
| API 권한 과다와 계정 탈취 | 제로 트러스트·세분화 **접근 제어** | 보안 위협 차단 |
| 자동 판정 오류와 이의 제기 부재 | 판정 근거·정정·**이의 신청 절차** | 자동 판정 신뢰 확보 |

#### 한줄 요약
- 표준, 동의, 복원력, 접근 제어, 이의 절차로 초연결 위험을 통제한다.

## Ⅶ. 결론

- 공급자 중심의 칸막이식 전자정부를 전면 혁신하여 공공 데이터 개방과 민관 초연결 플랫폼을 통해 국민 맞춤형 행정 서비스를 선제적으로 제공하는 **민관 협력 및 데이터 기반 국가 행정 혁신(Digital Platform Government / DPG Hub & Once-Only Principle / Public MyData & Zero Trust)의 차세대 국가 거버넌스 표준**으로 확고히 자리 잡았으며, 초거대 생성형 AI와 결합된 지능형 원스톱 행정 및 GovTech 혁신 생태계로 진화하는 가운데, 실무 디지털 플랫폼 정부 구현 및 연계 시에는 **기관 간 데이터 표준화와 메타데이터 관리(MDM)를 통한 완벽한 상호운용성 보장, Once-Only 원칙 기반의 구비서류 제로화 실현, 정보주체의 동의에 기반한 공공 마이데이터 전송 통제 및 전 구간 제로 트러스트 보안 아키텍처 결합**을 완벽히 구축하여 신뢰받는 디지털 복지 국가를 완성

#### 한줄 요약
- 재사용 가능한 행정정보는 동의·보안을 갖춰 다시 제출하지 않게 한다.
