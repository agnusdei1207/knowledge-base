## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **디지털 플랫폼 정부(DPG)**: 공공 데이터•기능과 민간 역량의 연결 모델이다.
- **응용 프로그래밍 인터페이스(API)**: 데이터•기능의 표준 요청•응답 접점이다.
- **정부 운영 모델**: 공공 데이터•서비스•민간 역량의 연결 체계이다.

</details>

- 정의/개념: **디지털 플랫폼 정부**는 공공 데이터•서비스와 민간 역량을 연결하는 **정부 운영 모델**이다.
- 배경/필요성: 기관별 칸막이로는 **정보 반복 제출•생애주기 서비스 단절** 해소하기 어렵다.

#### 한줄 요약
- **공공 데이터•행정 기능**을 표준 API로 연결해 **공동 활용**이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **마이데이터(MyData)**: 정보주체의 데이터 조회•전송•활용처를 통제한다.
- **민관 협력**: 민간 역량 활용과 보안•개인정보 책임을 통제한다.

</details>

- **데이터 연계**: 공통 API를 통한 기관 간 데이터 공유이다.
- **국민 중심**: 생애주기 맞춤 서비스와 **MyData** 기반 정보를 통제한다.
- **민관 협력**: 민간 기술과 창의성을 활용하되 보안•개인정보 통제를 병행이다.

#### 한줄 요약
- **기관 데이터 연계**와 **민간 기술**로 맞춤 행정을 제공한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **API 플랫폼**: 기관별 데이터와 행정 기능을 표준 접점으로 연결해 공동 활용하게 한다.
- **디지털 신원**: 온라인 신원 검증과 서비스별 접근 권한 정보이다.
- **정부기술(GovTech)**: 민간 기술로 공공 서비스를 개선하는 분야이다.
- **공공 데이터**: 표준•품질•권한•책임이 관리되는 행정 데이터이다.
- **민간 참여**: 공개 데이터•기능을 활용한 공공 서비스 공동 혁신이다.
- **보안**: 최소 권한과 접근 기록으로 데이터•기능의 오용을 차단하는 통제이다.
- **개인정보 보호**: 목적 제한과 정보주체 권리로 개인정보 처리를 통제하는 활동이다.

</details>

```text
                       [API 플랫폼]
                      /      |      \
          [공공 데이터] [디지털 신원] [민간 참여]
                      \      |      /
                    [보안•개인정보]
```

선의 의미: API 플랫폼은 공공 데이터, 디지털 신원, 민간 참여를 연결하며, 보안•개인정보 통제는 세 영역의 이용 경계를 함께 보호한다.

| 구성요소 | 책임 |
|:---|:---|
| 공공 데이터 | 기관 데이터의 **표준화•품질 관리** |
| API 플랫폼 | 데이터•행정 기능의 **표준 연결** |
| 디지털 신원 | 사용자 **신원•권한 관리** |
| 민간 참여 | 민간 활용과 **GovTech 연계** |
| 보안•개인정보 | 목적 외 이용 차단과 **접근 기록** |

#### 한줄 요약
- **API 플랫폼**이 데이터를 연결하고 **디지털 신원**으로 권한을 관리한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

</details>

```text
국민
   │ 맞춤 서비스 요청
   ▼
플랫폼
   │ 1. 이용 근거•권한 확인 요청
   ▼
국민
   │ 동의•권한 확인 회신
   ▼
플랫폼
   │ 2. 공공 데이터 조회 요청
   ▼
데이터기관
   │ 검증 데이터 반환
   ▼
플랫폼
   │ 융합 서비스 제공
   ▼
국민
```

**동작 원리**

1. **이용 근거•권한 확인 요청**: 법적 근거•동의•**접근 권한**을 검증한다.
2. **공공 데이터 조회 요청**: 공통 **API**로 기관 자료를 요청한다.

#### 한줄 요약
- **법적 근거•동의** 확인 후 데이터를 조회해 **원스톱 서비스**를 제공한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **디지털 플랫폼 정부(DPG)**: 공공 데이터•기능과 민간 역량의 연결 모델이다.
- **전자정부**: 기관별 행정 절차를 정보시스템과 온라인 채널로 제공하는 정부 운영 모델이다.

</details>

| 비교 기준 | 디지털 플랫폼 정부 | 전자정부 |
|:---|:---|:---|
| 적용 기준 | 부처 융합 **맞춤형 행정** | 개별 기관의 **업무 전산화** |
| 핵심 특징 | **데이터•API•민관 연결** | 기관별 **절차 온라인화** |
| 한계 | 데이터 **권한•책임 조정** | 기관 간 **서비스 단절** |

> 요약: 전자정부는 **업무 온라인화**, DPG는 **데이터•기능 연결**이 핵심이다.

#### 한줄 요약
- **전자정부**는 절차 온라인화, **DPG**는 데이터•기능을 연결한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **책임 경계**: 민관 장애•침해 대응의 데이터•운영 주체를 구분한다.
- **접근 이력 감사**: 개인정보 조회 기록과 승인 근거 대조이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별 **데이터 형식•품질** 차이 | 공통 표준•메타데이터와 **품질 책임자** 지정 | 기관 간 **연계 정확도** 향상 |
| 개인정보의 **목적 외 이용** 위험 | 법적 근거•동의•**최소 권한** 확인과 접근 이력 감사 | 정보주체 **권리•책임 추적** 확보 |
| 민관 서비스의 **책임 경계** 불명확 | 데이터•운영•사고 대응 책임을 **협약**으로 명시 | 장애•침해 사고의 **대응 속도** 향상 |

#### 한줄 요약
- 전입신고 정보의 **기관 연계**로 **반복 제출•개별 처리** 감소한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **한 번만 제출 원칙(Once Only)**: 제공한 행정 정보를 재요구하지 않는 원칙이다.
- **표준 API**: 동일한 요청•응답•보안 규칙의 연계 접점이다.

</details>

- 반복 제출은 **Once Only**, 연계•개인정보는 **표준 API•최소권한**을 적용한다.

#### 한줄 요약
- **법적 근거•책임**을 확정하며 **기관 연계•민간 활용**을 확대한다.
