## Ⅰ. 개요

<details>
<summary>핵심 용어(Key Terms)</summary>

- **디지털 플랫폼 정부(Digital Platform Government, DPG)**: 공공 데이터와 행정 기능을 표준 API로 연결하여 민간 역량과 융합하는 지능형 정부 운영 모델.
- **응용 프로그래밍 인터페이스(API)**: 정보시스템 간 데이터 및 기능 연동을 위한 표준 접점.

</details>

- 정의/개념: 공공 기능과 민간 기술을 연결하는 **정부 플랫폼 모델**
- 배경/필요성: 기관별 시스템으로 **반복 제출·서비스 단절** 발생

#### 한줄 요약
- **공공 데이터·API·민관 협력** 기반 맞춤 행정

## Ⅱ. 특징

<details>
<summary>핵심 용어(Key Terms)</summary>

- **마이데이터(MyData)**: 정보주체가 본인 데이터의 조회, 전송 및 활용처를 직접 통제하는 체계.
- **민관 협력(Public-Private Partnership)**: 민간의 기술 역량을 공공 서비스에 결합하고 책임을 상호 공유하는 방식.

</details>

- 공통 API 기반 기관 간 데이터 연계.
- 마이데이터 적용을 통한 정보주체의 데이터 주권 강화 및 통제권 보장.
- 민관 협력을 통한 GovTech 도입 및 책임 관리.

#### 한줄 요약
- 데이터 연계 및 민간 기술 융합을 통한 맞춤형 행정 서비스 제공.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **API 플랫폼(API Platform)**: 기관별 데이터와 행정 기능의 표준 연결 기반.
- **디지털 신원(Digital Identity)**: 온라인 신원 검증과 서비스 접근 권한.
- **정부기술(Government Technology, GovTech)**: 민간 기술 기반 공공 서비스 혁신.
- **공공 데이터(Public Data)**: 표준·품질·권한·책임이 관리되는 행정 데이터.
- **민간 참여(Private Participation)**: 공개 데이터·기능 기반 서비스 공동 혁신.
- **보안(Security)**: 최소 권한과 접근 기록 기반 오용 통제.
- **개인정보 보호(Privacy Protection)**: 목적 제한과 정보주체 권리 보장.

</details>

```text
                       [API 플랫폼]
                      /      |      \
          [공공 데이터] [디지털 신원] [민간 참여]
                      \      |      /
                    [보안•개인정보]
```

선의 의미: API 플랫폼은 공공 데이터, 디지털 신원, 민간 참여를 연결하며, 보안•개인정보 통제는 세 영역의 이용 경계를 함께 보호한다.

| 구성요소 | 책임 |
|:---|:---|
| 공공 데이터 | **공공 데이터**의 표준•품질•책임 관리 |
| API 플랫폼 | **API 플랫폼**으로 데이터•기능 연결 |
| 디지털 신원 | **디지털 신원**과 접근 권한 관리 |
| 민간 참여 | **민간 참여**와 **GovTech** 연계 |
| 보안•개인정보 | **보안**과 **개인정보 보호** 적용 |

#### 한줄 요약
- **API 플랫폼·디지털 신원·보안·민간 참여** 구조

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **이용 근거·권한 확인 요청**: 법적 근거·동의·접근 권한 검증.
- **공공 데이터 조회 요청**: 공통 API로 필요한 기관 자료 요청.
</details>

```text
국민
   │ 맞춤 서비스 요청
   ▼
플랫폼
   │ 1. 이용 근거•권한 확인 요청
   ▼
국민
   │ 동의•권한 확인 회신
   ▼
플랫폼
   │ 2. 공공 데이터 조회 요청
   ▼
데이터기관
   │ 검증 데이터 반환
   ▼
플랫폼
   │ 융합 서비스 제공
   ▼
국민
```

### 동작 원리

1. **이용 근거•권한 확인 요청**: 법적 근거•동의•접근 권한을 검증한다.
2. **공공 데이터 조회 요청**: 공통 **API**로 기관 자료를 요청한다.

#### 한줄 요약
- **권한 확인·공공 데이터 조회·융합 서비스** 제공

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **전자정부(e-Government)**: 기관별 행정 절차를 온라인으로 제공하는 정부 모델.

</details>

| 비교 기준 | 디지털 플랫폼 정부 | 전자정부 |
|:---|:---|:---|
| 적용 기준 | **DPG** | **전자정부** |
| 핵심 특징 | 데이터•API•민관 연결 | 기관별 절차 온라인화 |
| 한계 | 권한•책임 조정 | 기관 간 서비스 단절 |

> 요약: 전자정부는 업무 온라인화, DPG는 데이터•기능 연결이 핵심이다.

#### 한줄 요약
- **전자정부 절차 온라인화·DPG 데이터 연결** 구분

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어(Key Terms)</summary>

- **책임 경계(Responsibility Boundary)**: 민관 서비스 간의 데이터 관리 및 장애•침해 대응 주체를 구분하는 경계.
- **접근 이력 감사(Access Log Audit)**: 개인정보 접근 기록과 승인 근거를 대조하는 검증 활동.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별 데이터 품질 격차 | 공통 표준•메타데이터 적용 및 품질 관리자 지정 | 연계 정합성 확보 |
| 개인정보 목적 외 이용 | **접근 이력 감사** 수행 | 정보주체 권리 보장 |
| 민관 서비스 책임 불명확 | 데이터•운영•사고 대응 책임 범위 명시 | 사고 대응 효율성 향상 |

#### 한줄 요약
- 데이터 표준화와 책임 소재 명확화를 통해 안전한 민관 융합 서비스 제공.

## Ⅶ. 결론

<details>
<summary>핵심 용어(Key Terms)</summary>

- **한 번만 제출 원칙(Once Only Principle)**: 행정 정보 제공 시 재요구하지 않는 데이터 공유 원칙.
- **표준 API(Standard API)**: 데이터 연동을 위한 보안성 및 호환성이 확보된 표준 접점.

</details>

- 반복 제출 정보는 **한 번만 제출**, 기관 간 표준 API 공유

#### 한줄 요약
- **법적 근거·책임 경계·표준 API** 기반 데이터 공유
