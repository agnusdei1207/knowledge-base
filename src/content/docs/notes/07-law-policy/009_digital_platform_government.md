## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디지털 플랫폼 정부(DPG: Digital Platform Government / 대통령직속 디지털플랫폼정부위원회)**: 모든 데이터가 연결되는 '디지털 플랫폼' 위에서 공공기관의 분절된 행정 시스템과 민간의 혁신적 디지털 역량을 표준 오픈 API로 융합하여, 국민$\cdot$기업$\cdot$정부가 함께 사회 문제를 해결하고, 국민이 별도의 증명서를 발급받아 제출할 필요 없이 단 한 번의 신청으로 맞춤형 혜택을 선제적으로 제공받는 차세대 국가 지능형 정부 운영 모델.
- **부처별 칸막이 행정 및 구비서류 반복 제출 결함(Administrative Silo & Document Burden Defect)**: 각 부처와 지자체가 자체 웹사이트(홈택스, 정부24, 복지로 등)를 따로 운영하여 국민이 수십 개 사이트에 개별 회원가입하고 동일한 주민등록등본이나 납세증명서를 매번 종이로 발급받아 타 기관에 제출해야 하며, 민간 혁신 기업은 공공 데이터 API 접근이 차단되는 구조적 결함.

</details>

- 정의/개념: 공급자 중심의 분절된 전자정부를 넘어 수요자 중심의 민관 융합 플랫폼을 구축하기 위해 **DPG 허브(DPG Hub) 기반 데이터 연계 $\rightarrow$ 단 한 번 제출 원칙(Once-Only) 및 공공 마이데이터 적용 $\rightarrow$ 모바일 신분증(DID) 통합 인증 $\rightarrow$ 민관 협업 생태계(GovTech) 개방 $\rightarrow$ 제로 트러스트(Zero Trust) 보안** 을 집행하는 **국가 디지털 혁신 거버넌스 체계**
- 배경/필요성: 인공지능(AI)과 데이터 기술의 급성장에 발맞추어, 관료주의적 칸막이 행정을 철폐하고 국민 체감형 선제적 복지 전달 및 국가 행정의 데이터 과학화를 달성하기 위해 범정부 국정과제로 추진

#### 한줄 요약
- 디지털 플랫폼 정부는 DPG 허브와 공공 마이데이터를 통해 칸막이를 없애고 민관이 협력하여 선제적 맞춤 행정을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DPG 4대 핵심 추진 전략 (4 Strategic Goals)**:
  1. **오직 국민을 위한 서비스 (User-Centric)**: 알아서 챙겨주는 맞춤형 혜택 및 단 한 번의 통합 신청.
  2. **똑똑한 데이터 기반 행정 (Data-Driven)**: 관행과 직관이 아닌 실시간 빅데이터/AI 분석 기반의 과학적 정책 결정.
  3. **민관이 함께하는 혁신 생태계 (Co-Creation)**: 공공 데이터를 전면 개방하고 민간 앱(네이버, 카카오 등)에서 공공 서비스 이용.
  4. **안전하고 신뢰할 수 있는 플랫폼 (Zero Trust)**: 국가 사이버 안보 강화, 개인정보 주권 보장, 제로 트러스트 보안.

</details>

- **단 한 번 제출 원칙(Once-Only Principle)**: 행정기관이 이미 보유한 정보는 국민에게 다시 요구하지 않고 정부 내부 DPG 허브를 통해 기관 간 자동 공유
- **공공 마이데이터 및 자기정보결정권 보장**: 국민이 본인의 행정 데이터를 원하는 기관이나 민간 금융/복지 서비스로 직접 전송하도록 통제
- **민간 친화적 오픈 API 생태계(GovTech 육성)**: 여권 재발급, KTX 예매, 국립자연휴양림 예약 등 공공 독점 서비스를 민간 플랫폼 앱(토스, KB스타뱅킹 등)에 개방하여 서비스 융합

#### 한줄 요약
- 단 한 번 제출 원칙, 공공 마이데이터, 민관 융합 오픈 API, 제로 트러스트 보안을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **디지털 플랫폼 정부 4대 핵심 인프라 계층**:
  1. **DPG 허브 (Data & API Integration Hub)**: 민간-공공 데이터 및 서비스 API를 상호 중계하는 초연결 미들웨어 플랫폼.
  2. **통합 신원 인증 (Digital Identity)**: 블록체인 분산신원증명(DID) 기반 모바일 운전면허증 및 간편인증.
  3. **공공 마이데이터 유통망 (MyData)**: 본인정보 다운로드 및 전송 요구권 지원 체계.
  4. **제로 트러스트 보안 체계 (Security)**: 소프트웨어 정의 경계(SDP), mTLS 암호화, 접근 이력 감사.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 디지털 플랫폼 정부 (DPG) 초연결 민관 융합 아키텍처 ]              │

│       │                                                         │       │

│       │    └─ KTX 예매, 자동차 검사 예약, 맞춤형 복지 알림 통합 제공    │
│       │                                                         │       │
│       └─► [ 공공 포털 서비스 ] (통합 정부24 포털)               │       │

│  │ ├─ 공공 마이데이터 전송 관리   └─ 제로 트러스트 IAM 접근 제어     │  │
```

선의 의미: 국민이 모바일 신분증으로 민간/공공 앱에 접속하면 DPG 허브가 기관 간 데이터를 자동 조회하여 구비서류 없는 원스톱 서비스를 제공하는 구조

| DPG 핵심 구성요소 | 기능 및 역할 | 실무적 의의 | 비고 |
|:---|:---|:---|:---|
| **DPG 허브** | 민간-공공 데이터 및 서비스 API 연계 중계 | 부처 간 데이터 사일로 완전 타파 | Platform |
| **공공 마이데이터** | 국민 본인 정보 제3자 전송 요구권 보장 | 구비서류 제출 폐지 (종이 없는 행정)| MyData |
| **모바일 신분증** | 블록체인 DID 기반 온/오프라인 통합 인증 | 신원 도용 차단 및 자기주권 신원 | Identity |
| **민간 개방 API** | 공공 서비스를 민간 앱에 OpenAPI로 제공 | GovTech 생태계 및 민간 혁신 결합 | Open API |
| **제로 트러스트** | 모든 API 호출에 대한 연속적 검증 및 암호화| 공공망 개방에 따른 사이버 위협 방어| Security |

#### 한줄 요약
- DPG 허브, 공공 마이데이터, 모바일 신분증(DID), 민간 개방 API, 제로 트러스트 보안으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DPG 기반 선제적 맞춤형 복지 서비스 실행 5단계 프로세스**:
  1. 청년 구직자가 모바일 신분증(DID)으로 평소 자주 쓰던 민간 금융 앱에 로그인
  2. DPG 허브가 국세청 소득 데이터, 건강보험 자격 데이터를 백엔드에서 자동 교차 분석
  3. 청년에게 적합한 '청년도약계좌 및 월세 지원 혜택'을 맞춤형 푸시 알림으로 선제 추천
  4. 청년이 '동의 및 원클릭 신청' 버튼 1번만 터치 (단 한 번 제출 원칙 준수)
  5. 마이데이터 유통망을 통해 기관 간 검증 완료 ➔ 구비서류 0장으로 1초 만에 지원금 지급 승인

</details>

```text
1. [모바일 신분증(DID) 간편 로그인]
    ├─ 국민이 민간 은행 앱에서 블록체인 모바일 신분증으로 본인 인증
    └─ [인증 토큰이 DPG 허브로 안전하게 전달]
            │
            ▼
2. [DPG 허브의 데이터 융합 및 자격 스캔]
    ├─ DPG 허브가 행안부(나이/거주지), 국세청(소득), 건보공단(자격) API 호출
    └─ [백엔드 데이터 융합 분석 ➔ '청년 특별 복지 지원 대상자' 실시간 식별]
            │
            ▼
3. [선제적 맞춤형 알림 전송 (Push)]
    ├─ 민간 은행 앱 화면에 "OOO님, 청년 월세 지원금 월 20만원 대상자입니다" 알림 팝업
    └─ [지원 혜택 내용 및 필요 행정 정보 사전 자동 입력 완료]
            │
            ▼
4. [원클릭 신청 및 공공 마이데이터 전송 동의]
    ├─ 국민이 "신청하기 및 행정정보 제3자 제공 동의" 클릭
    └─ [단 한 번 제출 원칙(Once-Only): 주민등록등본, 소득증명서 제출 전면 생략]
            │
            ▼
5. [즉각적인 행정 처리 및 지원금 지급 완료]
    ├─ DPG 허브 ➔ 지자체 행정복지 시스템으로 검증 패킷 전송
    └─ [서류 검토 과정 0일 ➔ 신청 즉시 지원금 지급 대상 승인 완료]
```

**동작 원리**

1. **사전 선제적 행정(Proactive Administration)**: 국민이 법령을 찾아보고 신청해야 주던 과거 행정에서 탈피하여, 정부 플랫폼이 자격 요건을 먼저 계산하여 혜택을 알아서 안내
2. **단 한 번 제출(Once-Only)의 자동화**: 주민등록등본, 건강보험 납부확인서 등 정부가 이미 가지고 있는 100여 종의 서류를 공공 마이데이터 API로 즉시 조회하여 제출 의무 폐지
3. **민관 융합 인터페이스(GovTech Interface)**: 정부 전용 앱을 따로 설치할 필요 없이 국민의 90%가 이미 쓰는 카카오톡이나 네이버 앱에서 공공 행정을 완결
4. **제로 트러스트 보안(Never Trust, Always Verify)**: 모든 공공 API 트래픽에 mTLS 상호 인증과 토큰 기반 세분화 인가(Fine-grained RBAC)를 적용하여 데이터 유출 차단
5. **데이터 기반 정책 수립(Evidence-based Policy)**: 분산된 데이터를 가명 결합하여 교통, 복지, 재난 정책을 데이터 과학 모델로 설계

#### 한줄 요약
- 모바일 DID 인증, DPG 허브 데이터 융합, 선제적 알림, 원클릭 마이데이터 신청, 즉시 처리 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전자정부(e-Government) vs 디지털 플랫폼 정부(DPG) 패러다임 비교**:
  - 전자정부 (3.0): 정부 공급자 중심, 기관별 개별 포털, 종이 서류의 전자적 전환.
  - 디지털 플랫폼 정부 (DPG): 국민 수요자 중심, 민관 초연결 플랫폼, 구비서류 폐지 및 데이터 융합.

</details>

| 비교 항목 | 전통적 전자정부 (e-Government) | 디지털 플랫폼 정부 (DPG) |
|:---|:---|:---|
| **서비스 관점** | **정부 공급자 중심 (기관별 칸막이)** | **국민 및 기업 수요자 중심 (통합 플랫폼)**|
| **서비스 제공 방식** | 국민이 직접 신청해야 처리 (신청주의)| **데이터 분석 기반 알아서 챙겨주는 선제적 행정**|
| **구비 서류 제출** | **기관별 사이트에서 증명서 발급 후 제출**| **단 한 번 제출 원칙 (증명서 제출 전면 폐지)**|
| **민간과의 관계** | 정부 전용 포털 독점 운영 (정부24) | **민간 플랫폼(앱)과 공공 서비스 오픈 API 융합**|
| **데이터 활용** | 부처 간 데이터 공유 폐쇄 및 사일로 | **DPG 허브를 통한 전 부처 데이터 실시간 연계**|
| **보안 모델** | 물리적 망 분리 중심 경계 보안 | **데이터 중심 제로 트러스트 (Zero Trust) 보안**|

#### 한줄 요약
- 전자정부는 공급자 중심의 절차 온라인화, DPG는 수요자 중심의 데이터 초연결 및 민관 융합이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DPG 구현 실무 시 3대 위험 요소와 엔지니어링 대책**:

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별로 관리하는 데이터베이스의 메타데이터와 코드 체계가 달라 **DPG 허브를 통한 기관 간 데이터 융합 시 정합성이 깨지는 사일로 결함 발생** | **행안부 공공데이터 공통 표준 용어 및 범정부 마스터 데이터(MDM) 체계를 DPG 허브에 의무 강제 적용** | 데이터 상호운용성 및 연계 정합성 100% 확보 |

- 공통 표준 MDM으로 정합성을 잡고, 블록체인 영수증으로 프라이버시를 지키며, 서킷 브레이커로 민간 장애를 격리한다.

## Ⅶ. 결론

- 인공지능과 데이터 기반으로 국가 행정의 패러다임을 근본적으로 혁신하고 국민의 삶의 질을 획기적으로 개선하는 국가 대전환 전략인 **디지털 플랫폼 정부(DPG) 체계**는 단순한 전산화를 넘어 정부와 민간이 하나로 연결되는 지능형 플랫폼 국가의 절대적 토대이며, 실무 구현 시 **DPG 허브 기반의 데이터 칸막이 철폐**, **단 한 번 제출 원칙과 공공 마이데이터의 전면 확산**, **민간 오픈 API를 통한 GovTech 생태계 육성**, **제로 트러스트 기반의 철저한 개인정보 보호**를 완성하여 최고 수준의 국민 편익과 무결점 국가 디지털 인프라를 완성

#### 한줄 요약
- DPG 허브와 공공 마이데이터 및 민관 융합 오픈 API를 통해 선제적 맞춤형 디지털 플랫폼 정부를 완성한다.
