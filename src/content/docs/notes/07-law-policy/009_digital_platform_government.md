## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **디지털 플랫폼 정부(Digital Platform Government, DPG)**: 공공 데이터•기능과 민간 역량을 연결하는 정부 운영 모델이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **응용 프로그래밍 인터페이스(English, API)**: 데이터•기능의 표준 요청•응답 접점이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **정부 운영 모델(English, English)**: 공공 데이터•서비스•민간 역량의 연결 체계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- 정의/개념: 공공 데이터•서비스와 민간 역량을 연결하는 **디지털 플랫폼 정부(DPG)**이다.
- 배경/필요성: **정부 운영 모델**을 전환해 정보 반복 제출과 생애주기 서비스 단절을 해소한다.

#### 한줄 요약
- 공공 데이터•행정 기능을 **API**로 연결해 공동 활용한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **마이데이터(English, MyData)**: 정보주체가 데이터 조회•전송•활용처를 통제하는 방식이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **민관 협력(English, English)**: 민간 역량을 활용하면서 보안•개인정보 책임을 나누는 협력 방식이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- 공통 API로 기관 간 데이터를 연계한다.
- **MyData**로 정보주체의 조회•전송 권리를 통제한다.
- **민관 협력**으로 민간 기술을 활용하고 책임을 관리한다.

#### 한줄 요약
- 기관 데이터 연계와 민간 기술로 맞춤 행정을 제공한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **API 플랫폼(English, English)**: 기관별 데이터와 행정 기능을 표준 접점으로 연결해 공동 활용하게 하는 플랫폼이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **디지털 신원(English, English)**: 온라인 신원 검증과 서비스별 접근 권한 정보이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **정부기술(English, GovTech)**: 민간 기술로 공공 서비스를 개선하는 분야이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **공공 데이터(English, English)**: 표준•품질•권한•책임이 관리되는 행정 데이터이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **민간 참여(English, English)**: 공개 데이터•기능을 활용해 공공 서비스를 공동 혁신하는 활동이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **보안(English, English)**: 최소 권한과 접근 기록으로 데이터•기능의 오용을 차단하는 통제이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **개인정보 보호(English, English)**: 목적 제한과 정보주체 권리로 개인정보 처리를 통제하는 활동이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

```text
                       [API 플랫폼]
                      /      |      \
          [공공 데이터] [디지털 신원] [민간 참여]
                      \      |      /
                    [보안•개인정보]
```

선의 의미: API 플랫폼은 공공 데이터, 디지털 신원, 민간 참여를 연결하며, 보안•개인정보 통제는 세 영역의 이용 경계를 함께 보호한다.

| 구성요소 | 책임 |
|:---|:---|
| 공공 데이터 | **공공 데이터**의 표준•품질•책임 관리 |
| API 플랫폼 | **API 플랫폼**으로 데이터•기능 연결 |
| 디지털 신원 | **디지털 신원**과 접근 권한 관리 |
| 민간 참여 | **민간 참여**와 **GovTech** 연계 |
| 보안•개인정보 | **보안**과 **개인정보 보호** 적용 |

#### 한줄 요약
- **API 플랫폼**이 데이터를 연결하고 **디지털 신원**으로 권한을 관리한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **이용 근거•권한 확인 요청(English, English)**: 법적 근거•동의•접근 권한을 검증하는 단계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **공공 데이터 조회 요청(English, English)**: 공통 API로 필요한 기관 자료를 요청하는 단계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
</details>

```text
국민
   │ 맞춤 서비스 요청
   ▼
플랫폼
   │ 1. 이용 근거•권한 확인 요청
   ▼
국민
   │ 동의•권한 확인 회신
   ▼
플랫폼
   │ 2. 공공 데이터 조회 요청
   ▼
데이터기관
   │ 검증 데이터 반환
   ▼
플랫폼
   │ 융합 서비스 제공
   ▼
국민
```

### 동작 원리

1. **이용 근거•권한 확인 요청**: 법적 근거•동의•접근 권한을 검증한다.
2. **공공 데이터 조회 요청**: 공통 **API**로 기관 자료를 요청한다.

#### 한줄 요약
- 법적 근거•동의를 확인한 후 데이터를 조회해 원스톱 서비스를 제공한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **전자정부(e-Government, e-Government)**: 기관별 행정 절차를 정보시스템과 온라인 채널로 제공하는 정부 운영 모델이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

| 비교 기준 | 디지털 플랫폼 정부 | 전자정부 |
|:---|:---|:---|
| 적용 기준 | **DPG** | **전자정부** |
| 핵심 특징 | 데이터•API•민관 연결 | 기관별 절차 온라인화 |
| 한계 | 권한•책임 조정 | 기관 간 서비스 단절 |

> 요약: 전자정부는 업무 온라인화, DPG는 데이터•기능 연결이 핵심이다.

#### 한줄 요약
- **전자정부**는 절차 온라인화, **DPG**는 데이터•기능을 연결한다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **책임 경계(English, English)**: 민관 장애•침해 대응의 데이터•운영 주체를 구분하는 경계이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **접근 이력 감사(English, English)**: 개인정보 조회 기록과 승인 근거를 대조하는 감사이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별 데이터 형식•품질 차이 | 공통 표준•메타데이터와 품질 책임자 지정 | 연계 정확도 향상 |
| 개인정보 목적 외 이용 위험 | **접근 이력 감사** | 정보주체 권리 추적 |
| 민관 서비스의 **책임 경계** 불명확 | 데이터•운영•사고 대응 책임 명시 | 사고 대응 속도 향상 |

#### 한줄 요약
- 전입신고 정보의 기관 연계로 반복 제출•개별 처리를 줄인다 (핵심 원리 및 차별점을 기반으로 한 실무 맥락 적용).

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **한 번만 제출 원칙(English, Once Only)**: 제공한 행정 정보를 재요구하지 않는 원칙이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.
- **표준 API(English, English)**: 동일한 요청•응답•보안 규칙의 연계 접점이며, 이를 통해 실질적인 작동 방식과 실무적 이점을 제공한다.

</details>

- 반복 제출에는 **Once Only**, 연계에는 **표준 API**를 적용한다.

#### 한줄 요약
- 법적 근거와 책임을 확정하며 기관 연계•민간 활용을 확대 체계 적용 및 준수 적용.
