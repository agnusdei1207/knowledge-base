## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 부팅(Secure Boot)**: 전원 인가 시점부터 OS 로드까지 모든 단계의 소프트웨어 이미지에 대해 전자서명과 해시 무결성을 검증하는 부팅 메커니즘.
- **신뢰 사슬(Chain of Trust)**: 선행 부팅 단계가 차기 부팅 단계의 바이너리를 암호학적으로 검증하고 제어권을 넘기는 연쇄적 신뢰 연결 고리.

</details>

- 정의/개념: 시스템 전원 인가 시 하드웨어 RoT(Root of Trust)를 시작점으로 각 부팅 단계의 펌웨어 무결성과 서명을 검증하는 **신뢰 체인(Chain of Trust) 보안 부팅 기술**
- 배경/필요성: 운영체제 보안 기능이 시작되기 전 부트로더·커널이 변조되면 이후 검사와 권한 체계까지 우회 가능

#### 한줄 요약
- 하드웨어에 새겨진 불변의 암호 키를 바탕으로 1차 부트로더, 2차 부트로더, OS 커널이 위조되지 않았는지 꼬리를 물며 검사하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드웨어 RoT(Root of Trust)**: 물리적으로 수정이나 변조가 불가능하도록 칩 내부에 고정된 마스크 롬(Mask ROM)이나 eFuse 기반의 신뢰 시작점.
- **안티 롤백(Anti-Rollback)**: 서명이 정상이더라도 알려진 보안 취약점이 존재하는 과거 구버전 펌웨어로 다운그레이드되는 것을 차단하는 기법.

</details>

- 변조가 불가능한 **하드웨어 RoT(Mask ROM / eFuse)** 기반 신뢰 시작점 확립
- 공개키 비대칭 암호화(RSA/ECDSA) 기반 **단계별 전자서명 검증** 및 해시 무결성 확인
- 보안 버전 카운터(Monotonic Counter) 기반 **안티 롤백(Anti-Rollback)** 지원

#### 한줄 요약
- 하드웨어 롬에서 시작해 서명된 정품 펌웨어만 순서대로 실행하며, 구버전으로 되돌리는 다운그레이드 공격까지 차단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **eFuse(OTP, One-Time Programmable)**: 제조 공정 또는 양산 단계에서 전기적으로 단 한 번만 기록하여 영구히 보존되는 불휘발성 메모리 비트.
- **매니페스트(Manifest)**: 이미지 해시, 암호 서명, 버전 정보, 로딩 주소 등의 보안 메타데이터가 담긴 헤더 구조체.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 보안 부팅 신뢰 사슬 (Chain of Trust) 구조                   │
│                                                             │
│  [ 하드웨어 신뢰 뿌리 (RoT) ]                               │
│  ┌────────────────────────┐  (eFuse 내 OEM 공개키 해시)     │
│  │ 칩 내부 Mask ROM       │◄─────────────────────────────┐  │
│  │ (불변의 1차 부트로더)  │                              │  │
│  └───────────┬────────────┘                              │  │
│              │ 1. 검증 (Signature / Hash Check)          │  │
│  ┌───────────▼────────────┐                              │  │
│  │ 2차 부트로더 (U-Boot)  │ (외부 플래시 메모리 저장)    │  │
│  └───────────┬────────────┘                              │  │
│              │ 2. 검증 (Key Certificate Check)           │  │
│  ┌───────────▼────────────┐                              │  │
│  │ OS 커널 & DTB (Linux)  │ (외부 eMMC / SSD 저장)       │  │
│  └───────────┬────────────┘                              │  │
│              │ 3. 검증 (dm-verity / Rootfs Check)        │  │
│  ┌───────────▼────────────┐                              │  │
│  │ 시스템 앱 & 런타임 환경│ ──► [ 최종 안전 부팅 완료 ]  │  │
│  └────────────────────────┘                              │  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 칩 내부 Mask ROM에서 출발하여 상위 단계 펌웨어를 하나씩 검증하며 신뢰 사슬을 최상위 앱까지 확장

| 구성요소 | 책임 |
|:---|:---|
| 하드웨어 RoT (Mask ROM) | 전원 인가 시 최초 실행되며 eFuse의 OEM 공개키로 2차 부트로더의 서명 검증 |
| eFuse OTP 키 저장소 | 제조사 루트 공개키 해시(PK Hash) 및 보안 버전 롤백 방지 카운터 영구 보관 |
| 2차 부트로더 (BL2/U-Boot) | DDR 메모리를 초기화하고 OS 커널 이미지와 디바이스 트리의 무결성 검증 |
| 인증서 및 매니페스트 | 각 바이너리에 첨부된 해시, RSA/ECC 전자서명 및 버전 메타데이터 제공 |
| 보안 커널 (OS Kernel) | 파일시스템 무결성(dm-verity)을 검증하고 사용자 영역 샌드박스 실행 |

#### 한줄 요약
- Mask ROM, eFuse 공개키, 단계별 부트로더, 암호 서명 매니페스트가 신뢰 사슬의 연결 마디를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **dm-verity**: 리눅스 커널에서 블록 장치의 해시 트리를 구성하여 파일시스템이 읽힐 때마다 실시간으로 변조를 감지하는 기술.

</details>

```text
디바이스 전원 인가 (Power-On Reset)
      │
      ▼
1. 하드웨어 부팅
      │
      ▼
2. 전자서명 검증
      ├── [검증 실패] ──► 부팅 즉시 중단 및 보안 리셋 / 복구 모드 전환
      └── [검증 성공] ──► U-Boot로 제어권 인계
                             │
                             ▼
3. 버전 무결성 확인
                             │
                             ▼
4. 연쇄 검증 확장
                             │
                             ▼
5. 안전 부팅 완료
```

**동작 원리**

1. **하드웨어 부팅**: Mask ROM 코드가 실행되어 eFuse에 구워진 공개키 해시를 읽음
2. **전자서명 검증**: 신뢰 공개키로 서명 유효성을 확인하고 계산한 이미지 해시와 연결
3. **버전 무결성 확인**: 이미지 보안 버전이 허용 최저 버전 이상인지 확인
4. **연쇄 검증 확장**: 검증된 2차 부트로더가 커널을 검증하고, 커널이 시스템 앱을 검증
5. **안전 부팅 완료**: 모든 필수 검증이 성공하면 런타임 진입, 실패하면 정책에 따라 중단·복구

#### 한줄 요약
- RoT 기동 → 2차 부트로더 검증 → 안티 롤백 검사 → 커널 서명 검증 → 안전 런타임 진입 순으로 실행된다.

## Ⅴ. 종류 및 비교

| 부팅 보안 방식 | Secure Boot (보안 부팅) | Measured Boot (측정 부팅) | 일반 부팅 (Non-Secure) | Dual Boot (이중 부팅) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 임베디드 기기·스마트폰·차량 전장 | 엔터프라이즈 PC·서버 기밀 증명 | 비보안 저가 가전 및 테스트 장비 | 개발자용 다중 OS 선택 환경 |
| 핵심 특징 | 변조 감지 시 부팅 즉각 차단 | 모든 부팅 단계 해시를 TPM PCR에 누적 | 검증 없이 플래시 코드를 그대로 실행 | 파티션 선택에 따른 다중 OS 로드 |
| 한계 | 개발 단계 서명 키 관리 오버헤드 | 변조 코드가 일단 실행될 수 있음 | 악성 부트킷/루트킷 감염에 무방비 | 부팅 보안 정책 일관성 유지 곤란 |

#### 한줄 요약
- 변조 시 즉시 차단은 Secure Boot, 측정 후 원격 증명은 Measured Boot, 단순 부팅은 일반 부팅이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **글리치 공격(Fault Injection / Glitching)**: 클록이나 전압을 순간적으로 불안정하게 만들어 CPU의 `if(verify == OK)` 검증 분기 명령을 강제로 건너뛰게 하는 물리적 해킹.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제조사 서명 개인키 유출 시 **위조 펌웨어 전면 허용 위험** | **HSM(하드웨어 보안 모듈)** 기반 서명 인프라 및 키 철회(Revocation) 체계 수립 | 개인키 유출 방지 및 유출 키 무효화 |
| 취약점이 존재하는 과거 정품 펌웨어로 **다운그레이드(Rollback) 공격** | **eFuse 기반 하드웨어 안티 롤백(Monotonic Counter)** 강제 갱신 | 구버전 펌웨어 플래싱 차단 |
| 전압·클록 조작을 통한 **글리치 검증 우회** | 독립 중복 검증·결함 센서·실패 폐쇄형 제어 흐름 적용 | 단일 분기 오류로 검증이 우회될 가능성 감소 |
| 펌웨어 업데이트(OTA) 실패 시 **디바이스 영구 벽돌(Bricking)** | **A/B 듀얼 뱅크 파티션** 및 이전 정상 버전 자동 롤백 루틴 구현 | 무중단 안전 부팅 연속성 보장 |

#### 한줄 요약
- HSM으로 개인키를 지키고, eFuse로 롤백을 막으며, 이중 검증으로 글리치 공격을 방어한다.

## Ⅶ. 결론

- 비인가 코드 실행을 차단해야 하면 **RoT 기반 Secure Boot**, 상태 증명이 필요하면 Measured Boot 병행
- 업데이트 가능한 제품은 안티 롤백·키 철회·A/B 복구를 함께 설계해 보안과 복구 가능성 절충

#### 한줄 요약
- 하드웨어 신뢰 뿌리(RoT)에서 출발하는 암호학적 신뢰 사슬을 구축하여 악성코드의 부팅 단계 침투를 원천 차단해야 한다.
