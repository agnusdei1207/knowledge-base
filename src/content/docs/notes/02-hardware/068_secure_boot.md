## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Secure Boot(보안 부팅)**: 부팅 시 실행되는 모든 펌웨어와 부트로더의 디지털 서명을 순차적으로 검증하여 악성 코드의 개입을 원천 차단하는 보안 부팅 체계.
- **Root of Trust(신뢰의 뿌리, RoT)**: 변조가 불가능하도록 실리콘 칩에 각인된 불변의 부트 ROM 및 eFuse 기반 공개키 해시 저장소.
- **Chain of Trust(신뢰 사슬)**: 하드웨어 RoT에서 시작하여 1단계 부트로더(SPL), 2단계 부트로더(U-Boot/UEFI), OS 커널까지 이전 단계가 다음 단계의 서명을 검증하며 신뢰를 전파하는 구조.

</details>

- 정의/개념: 변조 불가능한 하드웨어 신뢰의 뿌리(Hardware Root of Trust, RoT)로부터 시작하여 다음 단계 부트로더 및 OS 커널의 디지털 서명과 버전을 연쇄적으로 검증(Chain of Trust)하여 인가된 펌웨어만 실행하는 보안 메커니즘
- 배경/필요성: 부팅 초기 단계에 침투하는 악성 부트로더/루트킷(Rootkit)에 의한 **시스템 권한 탈취 및 펌웨어 위변조를 원천 차단하고 시스템 무결성 보장**

#### 한줄 요약

- 하드웨어 RoT로부터 시작되는 **신뢰 사슬(Chain of Trust) 기반 펌웨어 무결성 검증 및 부팅**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Digital Signature(디지털 서명)**: 제조사의 비밀키로 펌웨어 해시를 암호화하여 생성한 전자 서명(ECDSA/RSA-PSS).
- **Anti-Rollback(안티 롤백)**: 칩 내부의 하드웨어 eFuse 모노토닉 카운터를 통해 과거의 취약한 정품 펌웨어로 다운그레이드하는 공격을 차단하는 기술.

</details>

- 비대칭 암호화(RSA/ECC) 전자서명 기반으로 펌웨어 출처 인증 및 **무결성(Integrity) 검증**
- 하드웨어 eFuse 비트를 태워 하한선 버전을 각인함으로써 과거 취약 버전으로의 복귀를 차단하는 **롤백 방지(Anti-Rollback)**
- 부트 ROM $\to$ 1차 부트로더 $\to$ 2차 부트로더 $\to$ OS 커널로 이어지는 **단계별 신뢰 사슬(Chain of Trust) 확장**

#### 한줄 요약

- **비대칭 암호 기반 서명 검증·eFuse 안티 롤백(Anti-Rollback)·하드웨어 불변 RoT 신뢰 사슬**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Boot ROM**: 칩 다이에 하드와이어드(Masked ROM)되어 수정이 불가능한 최상위 RoT 부팅 코드.
- **eFuse Array**: 칩 내부에 레이저나 고전압으로 영구 블로잉(Blowing)하여 공개키 해시 및 롤백 카운터를 보관하는 비휘발성 OTP(One-Time Programmable) 메모리.
- **Crypto Engine**: SHA-256 해시 연산 및 RSA/ECDSA 서명 검증을 고속 처리하는 하드웨어 가속기.

</details>

```text
[ Secure Boot 하드웨어 RoT 및 신뢰 사슬 아키텍처 ]
┌──────────────────────────────┐        ┌──────────────────────────────┐
│ 온칩 하드웨어 불변 보안 구역 │        │ 외장 플래시 메모리 (Flash)  │
│  [ 불변 부트 롬 (Boot ROM) ] │        │  [ 1차 부트로더 (SPL) + 서명]│
│  [ eFuse (Root PK Hash, NV) ]│        │  [ 2차 부트로더 (U-Boot)   ] │
│  [ 하드웨어 암호 가속기 ]    │        │  [ OS 커널 이미지 (Kernel) ] │
└──────────────┬───────────────┘        └──────────────┬───────────────┘
               │                                       │
               └─────────── [ 신뢰 사슬 검증 ] ────────┘
```

선의 의미: 불변 부트 ROM(Boot ROM), 신뢰 저장소(eFuse RoT PK Hash), 플래시 이미지 저장소(A/B 슬롯) 및 하드웨어 암호 가속 검증기 간의 보안 부팅 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 부트 롬 | 칩 공장에서 찍어내서 해커가 절대 위조할 수 없는, 가장 처음 실행되는 1차 부트로더 검증 코드 고정 보관소 |
| 신뢰 저장소 | 해커가 건드리지 못하게 칩 안에 박힌 퓨즈(eFuse)에 진짜 암호 키 지문(해시)과 **롤백 방지** 카운터를 영구 저장하는 금고 |
| 이미지 저장소 | 플래시 메모리에 들어있는 가짜일 수도 있는 펌웨어 덩어리들이며, 에러 날 때를 대비해 A와 B 두 슬롯으로 나누어 관리 |
| 서명 버전 검증기 | 하드웨어 암호화 가속기(해시 엔진)를 돌려 진짜 서명인지 확인하고 롤백 꼼수를 부렸는지 버전 숫자를 비교하는 판사 |

#### 한줄 요약

- **불변 부트 롬(Boot ROM)·신뢰 저장소(eFuse RoT)·이미지 저장소(A/B 슬롯)·하드웨어 암호 검증기**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **A/B Partitioning**: 펌웨어 갱신 도중 중단되거나 검증 실패 시 정상 부팅 가능한 다른 슬롯으로 자동 복구하는 듀얼 뱅크 파티셔닝 기법.

</details>

```text
[ Secure Boot 전원 인가 및 단계별 검증 시퀀스 ]
                         │
                         ▼
   [ 1. 전원 인가 시 Boot ROM 코드 실행 및 eFuse에서 Root PK Hash 로드 ]
                         │
                         ▼
   [ 2. 플래시 메모리에서 1단계 부트로더(SPL) 및 인증서/서명 로드 ]
                         │
                         ▼
   [ 3. 서명 검증 : SPL 공개키 해시 == eFuse PK Hash? & 서명 유효성 검증 ]
                         │
                         ▼
   [ 4. 안티 롤백 검증 : SPL 버전 >= eFuse 모노토닉 카운터 버전? ]
        /                                               \
   [ 예 (통과) ]                                     [ 아니오 (실패) ]
        │                                               │
   [ 5. SPL 로 제어권 이관 (신뢰 전파) ]           [ Fail-Safe 복구 슬롯 B 시도 ]
        │                                           (모두 실패 시 영구 정지)
        ▼
   [ 6. 2단계 부트로더 및 OS 커널에 대해 동일한 3~4번 검증 반복 수행 ]
```

**동작 원리**

1. **RoT 적재**: 전원 인가 시 Boot ROM이 하드웨어 eFuse에서 제조사 루트 공개키 해시와 롤백 카운터 로드
2. **이미지 획득**: 플래시 메모리에서 다음 단계 펌웨어 바이너리와 헤더 서명 블록 읽기
3. **디지털 서명 검증**: 하드웨어 암호 가속기로 해시를 계산하고 공개키 서명을 검증하여 위변조 여부 판정
4. **버전 비교(Anti-Rollback)**: 펌웨어 헤더의 버전이 eFuse 카운터보다 크거나 같은지 검사
5. **신뢰 사슬 전파**: 검증 성공 시 제어권을 다음 부트로더로 넘기고 커널 부팅까지 연쇄 검증 완료

#### 한줄 요약

- 전원 인가 $\to$ **Boot ROM 실행 & eFuse 공개키 해시 적재 $\to$ 펌웨어 전자서명 검증 $\to$ eFuse 안티 롤백 버전 검증 $\to$ 제어권 이관(Chain of Trust)**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Normal Boot vs Secure Boot vs Secure Boot with Anti-Rollback**:
  - Normal Boot: 검증 없음, 최고 속도, 위변조 취약
  - Secure Boot: 서명 검증, 무결성 보장, 구버전 다운그레이드 취약
  - Secure Boot + Anti-Rollback: 서명 + eFuse 버전 검증, 다운그레이드 완전 차단

</details>

| 비교 항목 | 일반 부팅 (Normal Boot) | 보안 부팅 (Secure Boot) | 보안 부팅 + 안티 롤백 (Anti-Rollback) |
|:---|:---|:---|:---|
| 검증 메커니즘 및 RoT | 검증 없음, 플래시 주소로 직접 점프 | 비대칭 공개키 기반 전자서명(RSA/ECDSA) 검증 | 서명 검증 + eFuse 모노토닉 카운터 버전 비교 |
| 방어 가능 위협 | 없음 (모든 물리/SW 변조에 무방비) | 비인가 악성 펌웨어/부트로더 변조 차단 | 서명 유효한 취약 구버전 다운그레이드 공격 차단 |
| 한계 및 적합 분야 | 보안 요구가 없는 초저가 완구/단순 센서 | 서명 키 관리 오버헤드 (스마트 기기) | eFuse 용량 한계 및 OTA 실패 시 롤백 설계 복잡 |

#### 한줄 요약

- 검증 없음은 **일반 부팅**, 변조 방지는 **Secure Boot**, 다운그레이드 방어는 **Anti-Rollback**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Key Revocation(키 폐기)**: 서명용 개인키가 외부에 유출되었을 때 칩의 특정 eFuse 비트를 태워 해당 키 ID를 영구 블랙리스트 처리하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 회사 직원이 서명 키를 통째로 유출해서 해커가 악성 펌웨어에 당당하게 진짜 서명을 박고 침투 | eFuse 기반 **키 폐기** 및 서명 키 롤오버를 가동하여 유출된 키의 지문(해시)을 뼛속 깊이 영구 무효화 | 털린 키로 도장 찍은 펌웨어를 싹 다 짭(가짜)으로 판정해 무효화하고 해커의 위장 침투 원천 차단 |
| 해커가 진짜 서명이 박혀있는 과거의 보안 뚫린 구버전 펌웨어를 훔쳐 들고 와서 강제 다운그레이드 공격 | eFuse 비트를 물리적으로 태워 숫자를 올리는 **롤백 방지** 카운터를 칩에 박아 구버전 실행을 무자비하게 거부 | 합법적 서명이 있어도 버전이 낮으면 얄짤없이 컷(Cut)해서 롤백 다운그레이드 꼼수 완벽 방어 |
| 서명 까보고 해시 돌리느라 펌웨어 검증 오버헤드가 터져서 시스템 부팅이 하루 종일 걸리는 답답한 사태 | 깡통 CPU 연산이 아니라 전용 하드웨어 암호화 가속기(Crypto Engine)를 연동시켜 해시 검증을 광속 처리 | 부팅 대기 지연을 극한으로 쥐어짜 최소화하여 블랙아웃 없는 무중단에 가까운 빠른 시스템 기동 보장 |

#### 한줄 요약

- **eFuse 기반 Key Revocation(키 폐기)·eFuse Monotonic Counter 안티 롤백·하드웨어 Crypto 가속 엔진**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Measured Boot(측정 부팅)**: Secure Boot와 병행하여 부팅 각 단계의 해시값을 TPM/vTPM PCR 레지스터에 기록(Extend)하여 원격 검증(Remote Attestation)을 제공하는 체계.

</details>

- 모바일, 전장(ISO 21434) 및 엔터프라이즈 서버 시스템에서 **하드웨어 RoT 기반 Secure Boot 및 Anti-Rollback 표준 필수 채택**

#### 한줄 요약

- **하드웨어 신뢰의 뿌리(RoT)와 롤백 방지(Anti-Rollback)**를 통한 시스템 부팅 무결성 확립
