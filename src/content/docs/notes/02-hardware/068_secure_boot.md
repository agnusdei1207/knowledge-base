## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 부팅(Secure Boot)**: 전원을 켜자마자 해커가 심어놓은 가짜 운영체제가 뜨는 걸 막기 위해, 부팅 단계마다 "너 진짜 정품 맞냐?"며 멱살 잡고 신분증(서명)을 깐깐하게 검사하는 절차이다.
- **신뢰의 뿌리(Root of Trust, RoT)**: "이 칩 안에 박힌 암호 키는 조물주(제조사)가 박아놓은 거라 무조건 진짜다!"라고 의심 없이 믿고 시작하는 하드웨어 최초의 뼛속 금고이다.
- **신뢰 사슬(Chain of Trust)**: 1차 부트로더가 2차를 의심하고, 2차가 커널을 의심하는 식으로, 꼬리에 꼬리를 물고 검사하며 시스템 전체로 믿음을 넓혀가는 연쇄 검증 구조이다.

</details>

- 정의: 변조가 절대 불가능한 하드웨어 **신뢰의 뿌리**(RoT)에서 시작하여 **신뢰 사슬**을 형성, 인가된 무결성 펌웨어만 부팅시키는 **보안 부팅**
- 배경: 아무나 부팅을 허락하면, 해커가 덮어씌운 악성 부트로더가 **운영체제(OS) 커널보다 먼저 시스템 권력을 통째로 삼켜버리는** 끔찍한 루트킷 참사가 터지기 때문

#### 한줄 요약

- 컴퓨터가 켜질 때 가짜 코드가 끼어들지 못하게, 뼛속에 박힌 진짜 키(신뢰의 뿌리)로 다음 코드를 계속 의심하고 검사하며(신뢰 사슬) 부팅하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **디지털 서명(Digital Signature)**: 해커가 코드를 한 줄이라도 고쳤으면 무조건 들통나도록, 제조사가 펌웨어 엉덩이에 쾅 찍어놓은 고도화된 암호화 도장이다.
- **무결성(Integrity)**: 공장에서 나올 때의 펌웨어 파일 상태와 단 1비트도 다르지 않고 완벽하게 똑같다는 것을 수학적 해시(SHA-256)로 증명하는 깐깐한 성질이다.
- **롤백 방지(Anti-Rollback)**: 해커가 옛날에 뚫렸던 구버전 정품 펌웨어를 들고 와서 몰래 덮어씌우려 할 때, "버전이 낮잖아!"라며 칩 안의 퓨즈(eFuse)를 확인해 단호히 쳐내는 방어 기술이다.

</details>

- 비대칭 키 전자서명을 통해 부팅 펌웨어가 짭(위조)인지 찐(정품)인지 출처를 인증하고 **무결성**을 가혹하게 검증함.
- 칩 안의 끊어진 퓨즈(eFuse) 숫자를 검사하여, 해커가 취약점이 있는 옛날 펌웨어로 덮어쓰는 꼼수인 **롤백 방지**를 강제함.
- 부트롬이 1차 부트로더를 까보고, 1차가 2차를 까보는 식으로 상위 단계가 하위 단계를 순차 검증하여 전개되는 **신뢰 사슬** 연계 구조를 지님.

#### 한줄 요약

- 전자도장(디지털 서명)으로 위조를 잡고, 퓨즈 숫자(롤백 방지)로 옛날 버전 꼼수를 잡아서, 꼬리에 꼬리를 무는 검증(신뢰 사슬)을 완성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **부트 롬(Boot ROM)**: 칩을 공장에서 찍어낼 때 아예 회로로 박아버려서, 해커가 칩을 쪼개지 않는 한 절대 코드를 바꿀 수 없는 철벽의 1차 부팅 구역이다.
- **신뢰 저장소(Trust Store)**: 해커가 건드리지 못하게 칩 안에 박힌 전자 퓨즈(eFuse)로, 한 번 태워 끊으면 다시는 못 붙이는 특성을 이용해 암호 키 지문과 버전을 영구 보관하는 금고이다.
- **이미지 저장소(Image Store)**: 펌웨어 파일들이 널브러져 있는 플래시 메모리 구역으로, 언제든 해커가 변조할 수 있는 위험 지대이다.
- **서명 버전 검증기(Signature/Version Verifier)**: 신뢰 저장소에서 진짜 키를 꺼내와서, 이미지 저장소에 있는 펌웨어 서명이 진짜인지 뼛속까지 검증하는 하드웨어 판사이다.

</details>

```text
[ 하드웨어 뼛속(RoT) 기반 펌웨어 무결성 십자포화 검증 아키텍처 ]
┌───── 철벽 하드웨어 보안 구역 ─────┐     ┌───── 변조 가능한 플래시 구역 ─────┐
│ [ 부트 롬 (불변의 1차 코드) ]    │     │ [ 이미지 저장소 (펌웨어 파일들) ] │
│               │                   │     │                 │                 │
│ [ 신뢰 저장소 (eFuse 진짜 키) ] ─┴─► [ 서명 버전 검증기 (암호화 가속기) ]
└───────────────────────────────────┘     └───────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **부트 롬** | 칩 공장에서 찍어내서 해커가 절대 위조할 수 없는, 가장 처음 실행되는 1차 부트로더 검증 코드 고정 보관소 |
| **신뢰 저장소** | 해커가 건드리지 못하게 칩 안에 박힌 퓨즈(eFuse)에 진짜 암호 키 지문(해시)과 **롤백 방지** 카운터를 영구 저장하는 금고 |
| 이미지 저장소 | 플래시 메모리에 들어있는 가짜일 수도 있는 펌웨어 덩어리들이며, 에러 날 때를 대비해 A와 B 두 슬롯으로 나누어 관리 |
| **서명 버전 검증기** | 하드웨어 암호화 가속기(해시 엔진)를 돌려 진짜 서명인지 확인하고 롤백 꼼수를 부렸는지 버전 숫자를 비교하는 판사 |

#### 한줄 요약

- 해커가 못 건드리는 부트 롬과 신뢰 저장소(eFuse)의 진짜 키를 가지고, 플래시 메모리(이미지 저장소)에 있는 펌웨어가 가짜인지 검증기에서 걸러낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **신뢰 기준(Trust Anchor)**: 검증의 잣대가 되는 절대 기준점. 즉, eFuse 금고 안에 깊숙이 박혀있는 제조사의 '진짜 공개키 해시(지문)' 값이다.
- **에이비 슬롯(A/B Slot)**: 펌웨어 업데이트하다 재수 없게 꼬여서 벽돌이 되는 걸 막기 위해, A방과 B방 두 개를 파놓고 한 방이 실패하면 다른 방으로 켜는 생존 구조이다.

</details>

```text
[ 전원 인가 및 펌웨어 신뢰 사슬 십자포화 검증 생존 흐름 ]
                               │
                               ▼
     [ 1. 신뢰 기준 적재: 부트 롬이 eFuse 금고를 열어 진짜 키 해시와 버전을 꺼내옴 ]
                               │
                               ▼
 ┌────────────────── 활성 슬롯 십자포화 검증 ──────────────────┐
 │ [ 2. 슬롯 선택: 업데이트된 A방을 열어 펌웨어를 꺼냄 ]             │
 │                             │                                 │
 │                             ▼                                 │
 │ [ 3. 서명 검증: 펌웨어 도장이 진짜인지 eFuse 키로 뼛속 검증 ]     │
 │                             │                                 │
 │                             ▼                                 │
 │ [ 4. 롤백 검증: eFuse에 박힌 버전 숫자보다 펌웨어 버전이 높은가? ]│
 │                  /                     \                      │
 │             (통과)                    (실패)                  │
 │               │                         └──► 다음 슬롯으로 반복 │
 │               ▼                                               │
 │ [ 5. 제어권 이관: 다음 2차 부트로더로 권력을 넘겨주고 부팅 속행 ] │
 └───────────────────────────────────────────────────────────────┘
```

### 동작 원리

1. 신뢰 기준 적재: 전원이 들어오면 **부트 롬** 코드가 eFuse 금고를 열어 **신뢰의 뿌리**(RoT) 진짜 키 해시와 **롤백 방지** 버전 숫자를 꺼내옴.
2. 부팅 슬롯 선택: **에이비 슬롯**(A/B Slot) 중 지금 우선적으로 구동해야 할 활성 파티션(예: A 슬롯)을 골라잡음.
3. 서명 및 키 폐기 십자포화 검증: 플래시에서 꺼낸 펌웨어의 **디지털 서명**이 찐인지 eFuse 키로 뼛속까지 검증하고, 털린 키인지(키 폐기) 확인.
4. 롤백 꼼수 검증: 펌웨어 헤더의 버전 숫자가 eFuse에 박힌 **롤백 방지** 숫자보다 높거나 같은지(과거 버전 덮어쓰기 금지) 깐깐하게 비교.
5. 제어권 이관(신뢰 사슬 확산): 모든 검증이 완결되면 하위 2차 부트로더나 OS 커널로 통제권을 넘겨주어 부팅을 속행함.

#### 한줄 요약

- 진짜 키를 꺼내서(신뢰 기준), 활성 슬롯의 서명과 버전을 검사하고, 통과하면 다음 놈한테 권력을 넘겨주며(신뢰 사슬), 꼬이면 복구 슬롯으로 도망간다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일반 부팅(Normal Boot)**: 아무 검증 없이 그냥 전원 들어오면 무조건 디스크 첫 번째 구역 코드를 무지성으로 실행해버리는 구시대적이고 취약한 부팅이다.

</details>

| 구분 | **일반 부팅** (Normal Boot) | **보안 부팅** (Secure Boot) | **보안 부팅 및 롤백 방지** (Anti-Rollback) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 검증이고 뭐고 그냥 전원 넣으면 가장 빨리 켜져야 하는 보안 깡통 IoT 디바이스 시 | 해커가 변조한 악성 펌웨어가 스마트폰이나 자동차를 통째로 털어먹는 것을 막아야 할 시 | 해커가 과거의 구멍 뚫린 정품 펌웨어를 들고 와서 덮어쓰기하는 교묘한 꼼수까지 막아야 할 시 |
| 아키텍처 핵심 구현 특징 | 아무런 검증 오버헤드 없이 플래시 주소로 냅다 점프해서 부팅 속도만 극한으로 뽑아냄 | 하드웨어 **신뢰의 뿌리**(RoT)에 박힌 진짜 키를 기반으로 **신뢰 사슬**을 돌려 무결성 서명 검증 수행 | 서명 검증은 기본이고, eFuse 퓨즈를 태워서 하한선 버전을 각인하는 **롤백 방지** 카운터 적용 |
| 극복해야 할 태생적 한계점 | 부트로더나 커널을 통째로 갈아치우는 루트킷 변조 해킹 공격에 아주 찰지게 무방비로 털림 | 해커가 유출된 진짜 서명 키로 찍어낸, 보안 빵구난 과거 버전 펌웨어로 다운그레이드 공격 시 무기력 | 무선 업데이트(OTA) 실패해서 꼬이면 양쪽 슬롯 다 뻗어버려 부팅 불능 벽돌 사태가 터질 위험 존재 |

#### 한줄 요약

- 일반 부팅은 해커한테 문을 열어주는 꼴이고, 보안 부팅은 문단속을 철저히 하는 거며, 롤백 방지는 옛날 열쇠로 문 따는 놈까지 잡아내는 극강의 방패이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **키 폐기(Key Revocation)**: 회사 직원이 비밀키를 잃어버렸을 때, "이 키로 도장 찍힌 펌웨어는 싹 다 가짜 처리해!"라고 eFuse 비트를 끊어 영원히 블랙리스트에 올리는 처형 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 회사 직원이 서명 키를 통째로 유출해서 해커가 악성 펌웨어에 당당하게 진짜 서명을 박고 침투 | eFuse 기반 **키 폐기** 및 서명 키 롤오버를 가동하여 유출된 키의 지문(해시)을 뼛속 깊이 영구 무효화 | 털린 키로 도장 찍은 펌웨어를 싹 다 짭(가짜)으로 판정해 무효화하고 해커의 위장 침투 원천 차단 |
| 해커가 진짜 서명이 박혀있는 과거의 보안 뚫린 구버전 펌웨어를 훔쳐 들고 와서 강제 다운그레이드 공격 | eFuse 비트를 물리적으로 태워 숫자를 올리는 **롤백 방지** 카운터를 칩에 박아 구버전 실행을 무자비하게 거부 | 합법적 서명이 있어도 버전이 낮으면 얄짤없이 컷(Cut)해서 롤백 다운그레이드 꼼수 완벽 방어 |
| 서명 까보고 해시 돌리느라 펌웨어 검증 오버헤드가 터져서 시스템 부팅이 하루 종일 걸리는 답답한 사태 | 깡통 CPU 연산이 아니라 전용 하드웨어 암호화 가속기(Crypto Engine)를 연동시켜 해시 검증을 광속 처리 | 부팅 대기 지연을 극한으로 쥐어짜 최소화하여 블랙아웃 없는 무중단에 가까운 빠른 시스템 기동 보장 |

#### 한줄 요약

- 도난당한 키는 eFuse 비트를 태워 영원히 버리고(키 폐기), 옛날 버전 꼼수도 카운터로 잡아내며(롤백 방지), 검증 시간은 암호화 칩으로 단축해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **부팅 승인 기준(Boot Authorization Criteria)**: 부팅을 허락할지 말지 판결을 내리는 3대 법전. 즉, '서명이 진짜냐?', '폐기된 키냐?', '버전이 롤백됐냐?'를 깐깐하게 따지는 잣대이다.

</details>

- **부팅 승인 기준** 원칙에 따라 하드웨어 **신뢰의 뿌리**(RoT) 중심의 **신뢰 사슬** 검증과 **롤백 방지**를 결합하여 무결성이 입증된 시스템 펌웨어만 구동 인가함

#### 한줄 요약
