## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 부팅(Secure Boot)**: 전원 인가 시점부터 OS 로드까지 모든 단계의 소프트웨어 이미지에 대해 전자서명과 해시 무결성을 검증하는 부팅 메커니즘.
- **신뢰 사슬(Chain of Trust)**: 선행 부팅 단계가 차기 부팅 단계의 바이너리를 암호학적으로 검증하고 제어권을 넘기는 연쇄적 신뢰 연결 고리.

</details>

- 정의/개념: 변조 불가능한 하드웨어 신뢰 뿌리에서 출발해 다음 단계를 순차 검증하며 **신뢰 사슬(Chain of Trust)**을 확장하는 **보안 부팅**
- 배경/필요성: OS 실행 전 부트로더 및 펌웨어 변조 시 **상위 보안 체계 전체 무력화 방지 불가**

#### 한줄 요약
- 하드웨어 RoT에서 시작하여 커널까지 각 부팅 단계의 서명을 연쇄적으로 검증하여 악성 부트킷을 원천 차단한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드웨어 RoT(Root of Trust)**: 물리적으로 수정이나 변조가 불가능하도록 칩 내부에 고정된 마스크 롬(Mask ROM)이나 eFuse 기반의 신뢰 시작점.
- **안티 롤백(Anti-Rollback)**: 서명이 정상이더라도 알려진 보안 취약점이 존재하는 과거 구버전 펌웨어로 다운그레이드되는 것을 차단하는 기법.

</details>

- **하드웨어 RoT**를 칩 내부에 고정하여 변조 불가능한 신뢰의 절대 시작점 확보
- 비대칭 공개키 암호 기반 디지털 서명 검증 및 SHA-256 해시 무결성 확인
- 하드웨어 eFuse 카운터 기반 **안티 롤백** 적용으로 취약 펌웨어 다운그레이드 방지

#### 한줄 요약
- 변조 불가능한 하드웨어 RoT와 eFuse 안티 롤백을 결합하여 서명된 정품 최신 펌웨어만 부팅을 허용한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **eFuse(OTP, One-Time Programmable)**: 제조 공정 또는 양산 단계에서 전기적으로 단 한 번만 기록하여 영구히 보존되는 불휘발성 메모리 비트.
- **매니페스트(Manifest)**: 이미지 해시, 암호 서명, 버전 정보, 로딩 주소 등의 보안 메타데이터가 담긴 헤더 구조체.

</details>

```text
[보안 부팅 신뢰 사슬(Chain of Trust)]
|-- 하드웨어 신뢰 뿌리 (Hardware RoT)
|   |-- 온칩 마스크 롬 (Mask ROM - 불변 1차 부트로더)
|   `-- eFuse OTP (루트 공개키 해시 및 안티 롤백 카운터)
|-- 2차 부트로더 (SPL/U-Boot - 외부 플래시 저장 및 메모리 초기화)
|-- OS 커널 및 디바이스 트리 (리눅스 커널 이미지 무결성 검증)
`-- 파일시스템 및 애플리케이션 (dm-verity 기반 블록 무결성)
```

선의 의미: 계층 및 단계별 암호학적 검증 흐름

| 구성요소 | 책임 |
|:---|:---|
| **하드웨어 RoT** | 최초 실행 코드로서 2차 부트로더의 디지털 서명 및 해시 무결성 검증 |
| **eFuse OTP** | OEM 루트 공개키 해시(ROTKH)와 최소 보안 펌웨어 버전 영구 보관 |
| 2차 부트로더 | 하드웨어 초기화 및 OS 커널/디바이스 트리 서명 검증 후 제어권 인계 |
| **매니페스트** | 각 부팅 이미지의 해시, 서명(RSA/ECC), 버전 정보 메타데이터 제공 |
| 보안 커널 | dm-verity를 통해 루트 파일시스템 무결성을 실시간 검증하고 앱 실행 |

#### 한줄 요약
- Mask ROM, eFuse, 2차 부트로더, OS 커널 및 dm-verity 파일시스템이 연쇄적인 검증 체계를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **dm-verity**: 리눅스 커널에서 블록 장치의 해시 트리를 구성하여 파일시스템이 읽힐 때마다 실시간으로 변조를 감지하는 기술.

</details>

```text
전원 인가 → 온칩 Mask ROM 실행 후 eFuse 공개키 해시 획득
        │
   2차 부트로더 이미지의 디지털 서명이 유효한가?
   ┌────┴─────┐
아니오          예
   │             │
부팅 즉각 차단   이미지 보안 버전이 eFuse 버전 이상인가? (안티 롤백)
및 복구 모드     ┌──┴───┐
   │          아니오     예
   │            │        │
   │      롤백 부팅 거부  제어권 인계 후 커널 서명 검증 단계로 진입
   └────┬───────┴────────┘
        │
   모든 신뢰 사슬 통과 시 dm-verity 마운트 및 런타임 진입
```

#### 한줄 요약
- 전원 인가 → 1차 RoT 서명/버전 검증 → 2차 부트로더 검증 → 커널 및 파일시스템 검증 후 부팅 완료 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Measured Boot(측정 부팅)**: 부팅을 차단하지 않고 각 단계의 해시를 TPM의 PCR 레지스터에 기록하여 원격 검증(Attestation)하는 방식.

</details>

| 부팅 보안 방식 | Secure Boot (보안 부팅) | Measured Boot (측정 부팅) | 일반 부팅 (Non-Secure) | Dual Boot (이중 부팅) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 임베디드 기기·스마트폰·차량 전장 | 엔터프라이즈 PC·서버 기밀 증명 | 비보안 저가 가전 및 테스트 장비 | 개발자용 다중 OS 선택 환경 |
| 핵심 특징 | 변조 감지 시 부팅 즉각 차단 | 모든 부팅 단계 해시를 TPM PCR에 누적 | 검증 없이 플래시 코드를 그대로 실행 | 파티션 선택에 따른 다중 OS 로드 |
| 한계 | 개발 단계 서명 키 관리 오버헤드 | 변조 코드가 일단 실행될 수 있음 | 악성 부트킷/루트킷 감염에 무방비 | 부팅 보안 정책 일관성 유지 곤란 |

#### 한줄 요약
- 임베디드 단말은 변조 시 즉각 실행을 차단하는 Secure Boot를, 서버 환경은 원격 신뢰 증명이 가능한 Measured Boot를 결합한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **글리치 공격(Fault Injection / Glitching)**: 클록이나 전압을 순간적으로 불안정하게 만들어 CPU의 `if(verify == OK)` 검증 분기 명령을 강제로 건너뛰게 하는 물리적 해킹.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서명 개인키 유출 시 위조 펌웨어 전면 허용 | HSM(Hardware Security Module) 기반 서명 인프라 및 키 철회 체계 | 개인키 유출 원천 차단 및 비상 무효화 경로 확보 |
| 취약한 구버전 펌웨어로 다운그레이드 공격 | 하드웨어 **eFuse 모노토닉 카운터** 기반 강제 안티 롤백 | 알려진 취약점 버전의 재설치 차단 |
| **글리치 공격**으로 서명 검증 조건문 우회 | 중복 검증 로직, 글리치 감지 센서, 결함 주입 시 리셋 회로 | 물리적 펄스 공격에 의한 분기 우회 방어 |
| OTA 업데이트 중 전원 차단 시 부팅 불능 | A/B 듀얼 파티션 구조 및 자동 롤백 부트로더 연동 | 소프트웨어 벽돌(Brick) 방지 및 가용성 유지 |

#### 한줄 요약
- HSM 키 관리, eFuse 안티 롤백, 글리치 방어 하드웨어 및 A/B 듀얼 파티션 OTA를 통해 완벽한 부팅 보안을 달성한다.

## Ⅶ. 결론

- 디바이스 무결성 보장을 위해 **하드웨어 RoT 기반 보안 부팅**을 구축하고, **안티 롤백 및 dm-verity**를 연동하여 종단 간 무결성 체계 완성

#### 한줄 요약
- 보안 부팅은 모든 펌웨어 및 OS 계층의 신뢰성을 담보하는 기기 보안의 최우선 출발점이다.
