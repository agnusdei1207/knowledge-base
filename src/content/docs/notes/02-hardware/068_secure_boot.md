## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 부팅(Secure Boot)**: 전원 인가 시점부터 OS 및 애플리케이션 기동까지, 부팅 각 단계의 소프트웨어 이미지 바이너리에 대해 하드웨어 신뢰 뿌리(RoT)를 기반으로 전자서명과 해시 무결성을 연쇄 검증하는 보안 기술.
- **신뢰 사슬(Chain of Trust)**: 선행 단계가 다음 바이너리를 검증한 뒤 제어권을 넘기는 검증 연결 구조.
- **하드웨어 신뢰 뿌리(Hardware Root of Trust, RoT)**: 물리적으로 수정이나 변조가 불가능하도록 칩 내부에 하드와이어드된 마스크 롬(Mask ROM)과 eFuse 기반의 신뢰 시작점.

</details>

- 정의/개념: 변조 불가능한 **하드웨어 신뢰 뿌리(Root of Trust)**에서 출발하여 각 단계의 전자서명과 무결성을 검증하며 **신뢰 사슬(Chain of Trust)**을 확장하는 **보안 부팅(Secure Boot)** 아키텍처
- 배경/필요성: OS 기동 전 최하위 부트로더/펌웨어 변조를 통한 부트킷(Bootkit)/루트킷(Rootkit)의 시스템 장악 및 상위 보안 계층 무력화 위험

#### 한줄 요약
- 보안 부팅은 하드웨어 RoT부터 각 부팅 단계의 서명을 연쇄 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **안티 롤백(Anti-Rollback)**: 전자서명이 유효하더라도 이미 보안 취약점이 공개된 과거 구버전 펌웨어로 다운그레이드되는 것을 하드웨어적으로 차단하는 방어 기법.

</details>

- 신뢰 출발점 보호: Mask ROM 및 eFuse에 OEM 루트 공개키 해시 저장
- 연쇄적 암호 무결성 검증: 비대칭 공개키 서명(RSA-3072 / ECC P-256)과 SHA-256 해시를 통해 다음 단계 바이너리의 위변조 즉각 탐지
- 하드웨어 **안티 롤백**: eFuse 카운터로 취약 구버전 실행 차단

#### 한줄 요약
- 불변의 하드웨어 RoT와 eFuse 안티 롤백을 결합하여 서명된 정품 최신 펌웨어만 부팅을 허용한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **eFuse OTP(One-Time Programmable)**: 반도체 제조 또는 양산 시 전기적 과전압으로 퓨즈를 영구 단선시켜 단 한 번만 기록되는 불휘발성 보안 메모리.
- **dm-verity**: 리눅스 커널에서 블록 디바이스의 머클 트리(Merkle Tree) 해시를 기반으로 파일시스템이 읽힐 때마다 실시간 무결성을 검증하는 하드웨어 가속 기술.

</details>

```text
[보안 부팅 신뢰 사슬(Chain of Trust) 아키텍처]
 ┌─ [하드웨어 신뢰 뿌리 (Hardware RoT)]
 │   ├─ 온칩 마스크 롬 (Mask ROM: 1단계 불변 부트로더 BL1)
 │   └─ [eFuse OTP] ── OEM 루트 공개키 해시(ROTKH) + 안티 롤백 카운터
 │
 ├─ [2차 부트로더 (BL2 / SPL)] ── DRAM 컨트롤러 초기화 및 BL3 서명 검증
 │
 ├─ [3차 부트로더 (BL3 / U-Boot, UEFI)] ── OS 커널 및 디바이스 트리 서명 검증
 │
 ├─ [OS 커널 및 드라이버 (Secure Kernel)] ── 시스템 파티션 무결성 검증
 │
 └─ [루트 파일시스템 및 애플리케이션] ── [dm-verity 기반 실시간 블록 무결성 보호]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 단계별 암호학적 신뢰 전파 흐름; 선행 계층이 차기 계층의 서명을 검증한 후에만 제어권을 이양함

| 구성요소 | 책임 |
|:---|:---|
| 온칩 Mask ROM | eFuse 키로 2차 부트로더 서명 검증 |
| **eFuse OTP** | 루트 키 해시와 최소 보안 버전 보관 |
| 2차 부트로더 | DRAM 초기화와 상위 부트로더 검증 |
| 3차 부트로더 | 커널과 디바이스 트리 서명 검증 |
| **dm-verity** | 머클 트리로 시스템 블록 무결성 검증 |

#### 한줄 요약
- eFuse OTP가 다시 쓸 수 있는 저장소를 대신해 루트 키 해시를 단선된 퓨즈로 붙들어 검증의 출발점 자체를 위조 대상에서 빼내고, dm-verity는 부팅 시점에서 끝나던 검증을 블록을 읽는 매 순간으로 옮겨 부팅 이후의 변조 공백을 메운다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **매니페스트(Security Manifest)**: 바이너리 해시, RSA/ECC 전자서명, 이미지 버전, 타깃 메모리 주소 정보가 포함된 암호학적 헤더 구조체.

</details>

```text
시스템 전원 인가와 Mask ROM 실행
                      │
                      ▼
BL2 매니페스트 서명 검증
    ┌──────────────────┴──────────────────┐
[ 전자서명 검증 실패 (변조 감지) ]    [ 전자서명 검증 성공 (정상) ]
    │                                     │
    ▼                                     ▼
부팅 중단 또는 복구 진입              보안 버전이 eFuse 카운터 이상인가?
    (하드웨어 벽돌화 방어)                ┌──────────┴──────────┐
                                        [ 버전 미달 (다운그레이드) ] [ 최신 버전 확인 ]
                                          │                     │
                                          ▼                     ▼
                                        롤백 부팅 거부          BL2 제어권 이양과 DRAM 초기화
                                           (공격 차단)          │
                                                                ▼
                                                             U-Boot와 커널 서명 연쇄 검증
                                                                │
                                                                ▼
                                                             dm-verity 마운트 후 런타임 진입
```

분기 결과: 서명과 **안티 롤백** 검증을 모두 통과해야만 차기 단계로 제어권이 넘어가며, 변조 감지 시 즉각 부팅을 차단함

#### 한줄 요약
- 단계마다 서명과 버전을 다시 확인하는 부팅 지연을 감수하는 대신, 신뢰의 근원을 변경 불가능한 Mask ROM 하나로 좁혀 이후 단계의 변조가 전파될 통로를 끊는다.

## Ⅴ. 종류 및 비교

| 부팅 보안 방식 | Secure Boot (보안 부팅) | Measured Boot (측정 부팅 / TPM) | 일반 비보안 부팅 |
|:---|:---|:---|:---|
| 변조 감지 시 동작 | 부팅 즉각 차단 및 실행 거부 | 부팅을 차단하지 않고 해시를 TPM에 누적 | 변조 여부 인지 못하고 그대로 실행 |
| 핵심 메커니즘 | 하드웨어 **RoT** 기반 디지털 서명 검증 | TPM PCR 레지스터 기반 원격 검증(Attestation)| 플래시 메모리 코드 단순 로드 |
| 주된 목적 | 악성 부트킷/루트킷의 칩 진입 차단 | 서버/기기의 무결성 상태 원격 증명 | 빠른 부팅 속도 및 개발 편의성 |
| 주요 적용 분야 | 스마트폰, 자동차 전장 ECU, IoT 단말 | 클라우드 데이터센터 서버, 기업용 PC | 프로토타입 개발 보드, 초저가 가전 |

#### 한줄 요약
- 임베디드 단말은 변조 시 즉시 부팅을 차단하는 Secure Boot를, 서버 환경은 원격 증명이 가능한 Measured Boot를 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **글리치 공격(Fault Injection / Glitching Attack)**: 전원 전압이나 클록에 미세한 전자기적 펄스를 순간 인가하여 CPU의 서명 검증 조건문 분기(`if (verify == OK)`)를 강제로 건너뛰게 만드는 물리적 해킹.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| OEM 서명 개인키 유출 시 위조 펌웨어 허용 위험 | **HSM 기반 서명 인프라와 다중 키 인증** | 키 노출 축소와 폐기 절차 지원 |
| 취약점이 발견된 과거 구버전 펌웨어로 다운그레이드 공격 | **하드웨어 eFuse 모노토닉 카운터 기반 강제 안티 롤백(Anti-Rollback)** | 알려진 취약 버전의 재설치 및 악용 차단 |
| 전압/클록 **글리치 공격(Fault Injection)**으로 검증 분기 우회 | **이중 조건 검증(Double Check) 및 글리치 감지 하드웨어 회로** | 물리적 펄스 공격에 의한 분기 우회 무력화 |

#### 한줄 요약
- 실무에서는 HSM 서명 관리로 키 유출을 막고, eFuse로 롤백을 차단하며, 이중 검증으로 글리치 공격을 방어한다.

## Ⅶ. 결론

- 하드웨어 불변 신뢰 뿌리(Mask ROM/eFuse RoT)를 기반으로 부팅 단계별 전자서명을 연쇄 검증하는 디바이스 보안의 절대적 출발점(**Chain of Trust** 표준)이며, 최근에는 eFuse 기반 **안티 롤백(Anti-Rollback)**과 TPM 연계 측정 부팅(Measured Boot/Remote Attestation) 및 글리치 주입 방어 회로와의 결합으로 종단 간 신뢰성을 완성하는 추세

#### 한줄 요약
- 보안 부팅은 모든 펌웨어와 OS의 신뢰성을 담보하는 기기 보안의 출발점이며, 하드웨어 RoT와 안티 롤백으로 완성된다.
