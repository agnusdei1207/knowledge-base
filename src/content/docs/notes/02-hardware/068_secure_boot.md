## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 부팅(Secure Boot)**: 전원 인가 직후 하드웨어 신뢰 루트(Root of Trust)에서 시작하여 다음 단계 부팅 펌웨어의 암호화 서명과 무결성을 단계별 검증한 후 제어권을 넘기는 메커니즘.
- **RoT(Root of Trust)**: 루트 공개키 해시와 최초 검증 로직을 Boot ROM·eFuse로 보호하는 신뢰의 시작점.
- **신뢰 사슬(Chain of Trust)**: 상위 검증 주체가 하위 펌웨어를 순차 검증(Boot ROM -> Primary Bootloader -> Secondary Bootloader -> OS Kernel)하며 신뢰를 확산하는 구조.

</details>

- 정의/개념: 변조 불가능한 하드웨어 **RoT** 기반으로 **신뢰 사슬**을 형성하여 인가된 무결성 펌웨어만 부팅시키는 **보안 부팅**
- 배경/필요성: 무검증 부팅은 변조된 부트로더가 **커널 이전에 권한 획득**

#### 한줄 요약

- 보안 부팅은 하드웨어 신뢰 루트에서 시작하여 **신뢰 사슬**을 형성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **디지털 서명(Digital Signature)**: 공개키 암호 알고리즘으로 펌웨어의 출처와 무결성을 검증하는 암호값.
- **무결성(Integrity)**: 바이너리 해시(SHA-256) 비교를 통해 저장소 내 펌웨어 이미지의 위변조 유무를 입증하는 성질.
- **롤백 방지(Anti-Rollback)**: eFuse/Monotonic Counter 수치를 검증하여 서명된 정상 이미지라도 취약점이 존재하는 구버전 펌웨어로의 강제 갱신을 차단하는 보안 기술.

</details>

- 비대칭 키 전자서명에 의한 부팅 펌웨어 출처 인증 및 **무결성** 검증
- 하드웨어 비휘발성 카운터(eFuse)에 근거한 구버전 강제 갱신 차단용 **롤백 방지**
- 상위 단계가 하위 단계를 순차 검증하여 전개되는 **신뢰 사슬** 연계

#### 한줄 요약

- **디지털 서명**과 **롤백 방지**를 모두 확인하는 부팅을 검증한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Boot ROM**: 칩셋 파운드리 제조 시 물리 Mask로 각인되어 최초 검증 코드를 수행하는 변경 불가능한 전용 ROM.
- **신뢰 저장소(Trust Store)**: eFuse, OTP(One-Time Programmable) 등 루트 공개키 해시 및 롤백 방지 버전을 영구 저장하는 보안 영역.
- **이미지 저장소(Image Store)**: 펌웨어 헤더, 서명 래퍼 및 실 바이너리가 결합된 Flash 메모리 영역.
- **서명·버전 검증기(Signature/Version Verifier)**: 해시 엔진 및 공개키 알고리즘을 통해 서명과 버전을 판정하는 암호 하드웨어/소프트웨어 모듈.

</details>

```text
[부트 ROM] -- [신뢰 저장소]
     |               |
[이미지 저장소] -- [서명•버전 검증기]
```

선의 의미: 부트 ROM 및 신뢰 저장소(eFuse)의 신뢰 기반이 서명/버전 검증기를 구동하여 이미지 저장소의 파티션을 수용하는 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 부트 ROM | **RoT** 하드웨어 최초 1차 부트로더 검증 코드 고정 보관 |
| 신뢰 저장소 | **eFuse/OTP** 내부 루트 키 해시 및 **롤백 방지** 카운터 영구 저장 |
| 이미지 저장소 | Flash 메모리 상의 Primary/Secondary 펌웨어 및 **A/B 슬롯** 관리 |
| 서명•버전 검증기 | HW 해시 엔진(SHA2) 및 RSA/ECC 서명 검증, 버전 비교 |

#### 한줄 요약

- **부트 ROM·신뢰 저장소**를 기반으로 다음 부팅 단계를 검증한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **신뢰 기준(Trust Anchor)**: 검증의 기준이 되는 eFuse 상의 Root Public Key Hash 수치.
- **A/B 슬롯(A/B Slot)**: 펌웨어 검증 실패 시 정상 작동 뱅크로 롤백 부팅하기 위한 듀얼 이미지 슬롯 구조.

</details>

```text
[전원 인가•부트 ROM]
          │
          ▼
1. 신뢰 기준 적재
          │
          ▼
┌────── 활성•복구 슬롯 순차 검증 ──────┐
│ 2. 부팅 슬롯 선택                     │
│          │                             │
│          ▼                             │
│ 3. 서명•키 폐기 검증                   │
│          │                             │
│          ▼                             │
│ 4. 보안 버전 검증                      │
│          │                             │
│          ┌────┴────┐                        │
│          │ 통과    │ 실패                   │
│          ▼         └── 다음 슬롯으로 반복   │
│ 5. 다음 단계 실행                      │
└─────┬─────────────────────────────────┘
      │ 모든 슬롯 실패
      ▼
 [제한된 복구 모드]
```

### 동작 원리

1. **신뢰 기준 적재**: 전원 인가 후 **Boot ROM** 코드가 eFuse 상의 **RoT** 루트 키 해시 및 **롤백 방지** 버전 인출.
2. **부팅 슬롯 선택**: **A/B 슬롯** 중 우선 구동 대상 활성 파티션 선택.
3. **서명·키 폐기 검증**: 인출된 펌웨어 이미지의 **디지털 서명**을 eFuse 루트 키로 검증 및 키 폐기(Key Revocation) 유무 체크.
4. **보안 버전 검증**: 펌웨어 헤더의 버전 수치가 eFuse **롤백 방지** 카운터 이상인지 비교.
5. **다음 단계 실행**: 검증 완결 시 하위 2차 부트로더/OS 커널로 제어권 이전 (**신뢰 사슬** 확산).

#### 한줄 요약

- 활성 슬롯 검증 실패 시 **A/B 슬롯**의 복구 이미지에 같은 검증을 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일반 부팅(Normal Boot)**: 검증 절차 없이 Flash의 진입점 주소로 직접 점프하여 펌웨어를 즉시 실행하는 구조.

</details>

| 구분 | 일반 부팅 (Normal Boot) | 보안 부팅 (Secure Boot) | 보안 부팅 + 롤백 방지 (Anti-Rollback) |
|:---|:---|:---|:---|
| 적용 기준 | 보안 요구가 없는 디바이스 시 | 펌웨어 위변조 및 미인가 코드 차단 시 | 취약점이 해결된 고보안 장비 구축 시 |
| 핵심 특징 | 검증 오버헤드 없음, 부팅 속도 극대화 | 하드웨어 **RoT** 및 **신뢰 사슬** 기반 서명 검증 | 서명 검증 + eFuse 카운터 기반 **롤백 방지** |
| 한계 | 부트로더·커널 루트킷 변조에 무방비 | 서명된 취약 구버전의 롤백 공격에 노출 | OTA 실패 시 버전 불일치로 부팅 불능 위험 |

#### 한줄 요약

- **서명 검증**은 변조·비승인 이미지를 차단하고, 롤백 방지는 서명된 취약 구버전까지 차단한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **키 폐기(Key Revocation)**: 비밀키 노출 시 해당 서명 키를 eFuse 비트 컷을 통해 영구 무효화하는 보안 대책.
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서명 키 유출 시 공격자가 악성 펌웨어에 유효 서명 | eFuse 기반 **키 폐기** 및 서명 키 롤오버 | 유출 키 기반 펌웨어 무효화 |
| 서명된 과거 취약 버전으로의 강제 다운그레이드 공격 | **롤백 방지** 카운터 및 OTA 성공 후 카운터 Commit 인가 | 롤백 공격 차단 |
| 펌웨어 검증 오버헤드로 인한 부팅 지연 발생 | 하드웨어 암호화 가속기(Crypto Engine) 연동 | 부팅 대기 지연 최소화 |

> 사례: eFuse 기반 **RoT** 및 **Anti-Rollback** 적용을 통한 모바일/차량 보안 부팅 구현

#### 한줄 요약

- 새 슬롯의 정상 부팅을 확인한 뒤 **보안 버전 확정**을 수행하고, 실패하면 기존 검증 슬롯으로 복구한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **부팅 승인 기준(Boot Authorization Criteria)**: 무결성 검증, 키 폐기 여부 및 Anti-Rollback 버전에 근거한 부팅 인가 기준.

</details>

- **부팅 승인 기준**에 따라 하드웨어 **RoT** 중심의 **신뢰 사슬**과 **롤백 방지**를 결합하여 무결성이 입증된 시스템 펌웨어만 구동 인가

#### 한줄 요약

- 서명·키 폐기·보안 버전을 통과한 펌웨어만 실행하고 실패 시 복구 슬롯으로 전환한다.
