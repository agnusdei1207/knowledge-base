## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에게 물리 메모리와 독립된 고유의 논리 주소 공간을 제공하여, 물리적 메모리 크기 이상의 주소 지정, 비연속 메모리 할당 및 프로세스 간 메모리 완전 격리를 실현하는 메모리 관리 기법.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 블록(가상 페이지, 물리 프레임)으로 균등 분할하여 외부 단편화 없이 비연속적으로 매핑하는 기법.
- **세그멘테이션(Segmentation)**: 프로그램의 논리적 의미 단위(코드, 데이터, 스택, 힙 등)에 따라 가변 크기의 세그먼트로 메모리를 분할하고 논리적 보호 및 공유를 제어하는 기법.

</details>

- 정의/개념: 프로세스별 가상 주소를 **페이징** 또는 **세그멘테이션** 기반 물리 메모리에 매핑하는 메모리 관리 체계
- 배경/필요성: 연속 물리 할당만으로는 흩어진 빈 공간을 모을 수 없어, 물리 메모리보다 큰 주소 공간도 프로세스 간 격리도 제공 불가

#### 한줄 요약
- **가상 메모리가** 제공하는 것은 큰 공간이 아니라 물리 배치로부터의 독립이며, 용량 확장은 그 독립성에서 파생된 부수 효과에 가깝다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로그램 실행 시 모든 페이지를 미리 메모리에 적재하지 않고, CPU가 실제로 해당 페이지를 참조(Access)하여 페이지 폴트가 발생할 때만 물리 메모리로 적재하는 기법.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소 공간상에서 연속된 페이지들을 물리 메모리의 흩어져 있는 임의의 빈 물리 프레임에 분산 배치하는 메모리 할당 방식.
- **메모리 보호(Memory Protection)**: 페이지 테이블이나 세그먼트 기술자에 읽기(R), 쓰기(W), 실행(X) 권한 비트를 설정하여 불법적인 메모리 변조나 코드 실행을 하드웨어적으로 차단하는 보안 기능.

</details>

- **요구 페이징** 기반 참조 전 페이지를 적재하지 않아 초기 메모리 사용량 감소
- **비연속 할당** 기반 물리 메모리의 분산 프레임을 연속 가상 공간으로 투명하게 제공
- 페이지·세그먼트별 **메모리 보호** 기반 프로세스 간 불법 접근 차단

#### 한줄 요약
- **요구 페이징** 및 **메모리 보호**는 같은 변환 표를 공유하므로, 성능 기법과 보안 기법이 한 자료구조에 얹혀 있다는 점이 이 설계의 강점이자 공격 표면이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블(Page Table)**: 가상 페이지 번호(VPN)를 물리 프레임 번호(PPN) 및 접근 제어 비트와 매핑하여 관리하는 메모리 상의 변환 테이블.
- **세그먼트 기술자(Segment Descriptor)**: 각 세그먼트의 물리 기준 시작 주소(Base), 세그먼트 크기 한계(Limit), 접근 제어 권한 및 특권 레벨을 정의하는 디스크립터 구조체.
- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU가 출력하는 논리/가상 주소를 물리 주소로 실시간 변환하고 권한 위반 여부를 검사하는 하드웨어 장치.

</details>

```text
[가상 메모리 관리]
├─ MMU
│  ├─ 페이징 변환 (페이지 테이블)
│  ├─ 세그멘테이션 변환 (세그먼트 기술자)
│  └─ 결합 변환 (세그먼트 선택 후 페이지 변환)
└─ 물리 프레임
```

선의 의미: 가지(`├─`)는 MMU가 지원하는 대안·결합 변환 구조와 물리 저장 대상

| 구성요소 | 책임 |
|:---|:---|
| **MMU** | 가상→물리 주소 변환·접근 권한 검사 |
| 페이지 테이블 | 가상 페이지 번호·물리 프레임 번호·권한 매핑 |
| 세그먼트 기술자 | 논리 세그먼트의 기준 주소·크기·권한 관리 |
| 물리 프레임 | 변환된 실제 데이터·코드 저장 |

#### 한줄 요약
- **세그먼트 기술자는** 프로그램의 의미 단위를 알고 **페이지 테이블은** 모르므로, 보호를 정교하게 하려면 전자가 유리하고 배치를 단순하게 하려면 후자가 유리하다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: CPU가 요청한 페이지가 물리 메모리에 적재되어 있지 않거나(Invalid/Non-Present) 권한을 위반했을 때 발생하는 하드웨어 트랩(Trap) 예외.
- **명령어 재시작(Instruction Restart)**: OS가 페이지 폴트를 처리하여 디스크에서 해당 페이지를 물리 메모리로 적재 완료한 후, 중단되었던 CPU 명령어를 처음부터 온전히 재실행하는 복구 메커니즘.

</details>

```text
CPU 가상 주소 접근
      │
      ▼
1. MMU 변환 및 권한 확인
      │
      ├─ 권한 위반 ─────────→ 접근 예외 처리
      ├─ 상주·권한 허용 ────→ 물리 메모리 접근
      └─ 비상주 ────────────→ 2. 페이지 폴트 및 페이지 적재
                                         │
                                   3. 명령어 재시작
```

분기 결과: 권한 위반은 프로그램 오류로 확정되어 되돌릴 수 없지만, 비상주는 정상 동작이라 **페이지 폴트** 처리 후 **명령어 재시작**을 통해 정상 상태로 재개

#### 한줄 요약
- 명령어를 도중에 이어 하지 않고 처음부터 다시 실행한다는 규칙이 가상 메모리를 성립시키며, 이 때문에 명령어는 중간 부작용을 남기지 않도록 설계돼야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 페이징 기법에서 프로세스에 할당된 고정 크기 페이지 블록의 마지막 공간이 실제 데이터 크기보다 커서 내부에서 발생하는 메모리 낭비 현상.
- **외부 단편화(External Fragmentation)**: 세그멘테이션 기법 등에서 가변 크기 블록의 할당과 해제가 반복되어 총 여유 공간은 충분하나 연속된 공간이 부족하여 새 세그먼트를 적재하지 못하는 현상.
- **페이지 세그멘테이션(Paged Segmentation)**: 프로그램을 논리적 가변 세그먼트로 먼저 분할한 후, 각 세그먼트 내부를 다시 고정 크기 페이지로 쪼개어 외부 단편화를 제거하고 논리적 보호와 고정 배치를 결합한 방식.

</details>

| 메모리 관리 방식 | 페이징 | 세그멘테이션 | 페이지 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | 고정 단위·비연속 배치 우선 | 논리 단위 보호·공유 우선 | 논리 구분과 고정 배치 동시 필요 |
| 핵심 특징 | 고정 크기 페이지·프레임의 **비연속 할당** | 가변 세그먼트를 기준·한계 레지스터로 관리 | 세그먼트 내부에 페이지 테이블을 한 단 추가 |
| 한계 | **내부 단편화** 및 페이지 테이블 메모리 비용 | **외부 단편화** 및 가변 배치 관리 복잡도 | 변환 단계 증가로 지연·관리 부담 상승 |

#### 한줄 요약
- 페이징이 이긴 이유는 보호가 더 나아서가 아니라 단편화를 **내부 단편화**라는 예측 가능한 형태로 바꿨기 때문이며, 예측 가능성이 곧 관리 가능성이었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: 프로세스 생성(fork) 시 부모의 메모리 페이지를 즉시 복제하지 않고 읽기 전용으로 공유하다가, 어느 한 프로세스가 쓰기 연산을 시도하는 시점에만 해당 페이지만 독립 복제하는 최적화 기법.
- **쓰레싱(Thrashing)**: 활성 프로세스들의 작업 집합(Working Set)을 수용하기에 물리 메모리가 부족하여, 프로세서가 실제 연산 시간보다 페이지 교체(Page In/Out) 입출력에 대부분의 시간을 소모하여 성능이 급격히 저하되는 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 **쓰레싱** 발생 | 작업 집합 기준 프레임 배분·동시 실행량 조절 | 페이지 입출력 폭증 완화 |
| 큰 페이지가 **내부 단편화** 유발 | 연속 접근 영역에만 대형 페이지 선택 적용 | 커버리지·공간 효율 균형 |
| 프로세스 생성 시 전체 메모리 복사 비용 | **CoW** 기반 페이지 공유 | 초기 생성 시간·메모리 사용 감소 |
| 세그멘테이션 가변 배치의 **외부 단편화** | 페이징 결합·물리 프레임 연속성 보장 | 배치 실패·관리 부담 완화 |

#### 한줄 요약
- **쓰레싱**만은 다른 셋과 성격이 달라 국소적 조정으로 해결되지 않으며, 동시 실행량을 줄이는 것 말고는 물러설 방법이 없다.

## Ⅶ. 결론

- 현대 범용 시스템은 **페이징**을 기본으로 하고 페이지 권한으로 보호하며, 세그멘테이션은 논리 구획을 하드웨어 주소 변환에 반영해야 하는 호환·특수 환경에 한정

#### 한줄 요약
- **세그멘테이션이** 주소 변환에서 밀려난 뒤에도 논리 구획 개념 자체는 페이지 권한 비트로 살아남았으므로, 사라진 것은 개념이 아니라 구현 방식이다.
