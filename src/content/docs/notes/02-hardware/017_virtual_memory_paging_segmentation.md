## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에게 연속된 독자 논리 주소 공간을 제공하여 물리 메모리 용량의 한계를 극복하고, 프로세스 간 메모리 완전 격리 및 비연속 물리 메모리 할당을 실현하는 운영체제-하드웨어 협력 메모리 관리 체계.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 블록(가상 페이지, 물리 프레임)으로 균등 분할하여 외부 단편화 없이 비연속적으로 매핑하는 기법.
- **세그멘테이션(Segmentation)**: 프로그램의 논리적 모듈 단위(코드, 데이터, 스택, 힙)에 따라 가변 크기의 세그먼트로 메모리를 분할하고 논리적 보호와 공유를 제어하는 기법.

</details>

- 정의/개념: 프로세스별 가상 주소를 **페이징(Paging)**의 고정 크기 블록 또는 **세그멘테이션(Segmentation)**의 가변 논리 단위로 분할하여 물리 DRAM 프레임에 매핑하는 **가상 메모리 관리 아키텍처**
- 배경/필요성: 물리 메모리의 직접 연속 할당 방식에 따른 **외부 단편화 발생, 물리 메모리 용량 제약 및 프로세스 간 메모리 보호 불가** 극복

#### 한줄 요약
- 가상 메모리는 물리 배치로부터 프로세스를 분리하여 비연속 할당, 메모리 보호, 용량 확장을 실현하는 핵심 시스템 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로그램 실행 시 전체를 미리 메모리에 적재하지 않고, 실제 접근이 발생하여 페이지 폴트가 일어날 때만 해당 페이지를 물리 메모리로 적재하는 기법.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소 공간상에서 연속된 페이지들을 물리 메모리의 임의의 빈 물리 프레임에 흩어져 배치하는 방식.
- **메모리 보호(Memory Protection)**: 페이지 테이블이나 세그먼트 기술자에 읽기(R), 쓰기(W), 실행(X) 권한 비트를 설정하여 불법 접근을 하드웨어적으로 차단하는 보안 기능.

</details>

- 메모리 활용 극대화: **요구 페이징(Demand Paging)**을 통해 필요한 페이지만 메모리에 적재하여 물리 메모리 낭비 제거
- 유연한 공간 배치: **비연속 할당**을 통해 물리 메모리의 분산된 빈 프레임들을 프로세스에게 하나의 연속된 가상 공간으로 투명하게 제공
- 하드웨어 접근 통제: 페이지 테이블 엔트리(PTE) 및 세그먼트 기술자의 **메모리 보호(R/W/X)** 비트를 기반으로 프로세스 간 메모리 침범 원천 차단

#### 한줄 요약
- 페이징은 외부 단편화를 없애고 배치를 단순화하며, 세그멘테이션은 프로그램 논리 구조에 맞춘 정밀한 권한 보호와 공유를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 내부에 위치하여 가상 주소를 물리 주소로 실시간 변환하고 권한 위반을 검사하는 하드웨어 유닛.
- **페이지 테이블(Page Table)**: 가상 페이지 번호(VPN)를 물리 프레임 번호(PPN) 및 접근 제어 비트와 매핑하여 DRAM에 상주하는 OS 커널 정본 테이블.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 물리 기준 시작 주소(Base), 크기 한계(Limit), 접근 권한(R/W/X)을 정의하는 디스크립터 구조체.

</details>

```text
[CPU 코어 (가상 주소 발행)]
 └─ [메모리 관리 장치 (MMU)]
     ├─ [세그멘테이션 유닛] ──► 세그먼트 테이블 (Base + Limit 검증) ──► [선형 주소 도출]
     │                                                                       │
     └─ [페이징 유닛] ◄───────────────────────────────────────────────────────┘
         ├─ TLB (고속 주소 변환 캐시: CAM + SRAM)
         └─ 페이지 테이블 워커 (TLB 미스 시 순회) ──► [DRAM 다단계 페이지 테이블] ──► [물리 DRAM 프레임]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; x86 등에서는 세그멘테이션을 거친 선형 주소가 다시 페이징 유닛으로 입력됨

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **MMU** | CPU 내부 핵심 장치 | 가상 주소의 물리 주소 실시간 변환 및 접근 권한 검사 총괄 | 하드웨어 기반 주소 변환 |
| **세그먼트 테이블**| DRAM (GDTR/LDTR 가리킴)| 세그먼트별 기준 주소(Base), 한계(Limit), 특권 레벨 관리 | 가변 크기 논리 구획 정의 |
| **다단계 페이지 테이블**| DRAM (CR3/TTBR 가리킴) | 가상 페이지 번호(VPN)와 물리 프레임 번호(PPN) 매핑 정본 | 고정 4KB/2MB 단위 매핑 |
| **물리 프레임** | 메인 메모리 (DRAM) | 실제 기계어 코드 및 사용자 데이터가 상주하는 물리 블록 | 비연속 분산 배치 |

#### 한줄 요약
- 가상 메모리는 CPU 내부 MMU(TLB, 워커)와 DRAM 상의 페이지/세그먼트 테이블이 협력하여 물리 프레임으로의 투명한 주소 변환을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: CPU가 접근하려는 페이지가 물리 메모리에 적재되어 있지 않거나(Present=0) 권한을 위반했을 때 발생하는 하드웨어 트랩 예외.
- **명령어 재시작(Instruction Restart)**: OS가 페이지 폴트를 처리하여 디스크에서 물리 프레임으로 적재 완료한 후, 중단되었던 CPU 명령어를 처음부터 온전히 재실행하는 복구 메커니즘.

</details>

```text
1. CPU 가상 주소 접근 (VPN + Offset)
                      │
                      ▼
2. MMU 변환 및 권한 검사 (TLB 조회 / Page Walk)
   ┌──────────────────┴──────────────────┐
[ 매핑 유효 및 권한 일치 ]            [ 매핑 부재 (Present=0) 또는 권한 위반 ]
   │                                     │
   ▼                                     ├─ 권한 위반(W on RO 등) ➔ Segfault (프로세스 종료)
3. 물리 주소(PPN + Offset) 생성          │
   ➔ 캐시 및 DRAM 데이터 접근            └─ 부재 ➔ 4. 페이지 폴트(Page Fault) 하드웨어 트랩 발생
                                                   │
                                                   ▼
                                         5. OS 커널 트랩 핸들러: 디스크에서 빈 프레임으로 적재
                                                   │
                                                   ▼
                                         6. 페이지 테이블 및 TLB 엔트리 갱신
                                                   │
                                                   ▼
                                         7. 명령어 재시작(Instruction Restart) 및 정상 실행
```

분기 결과: **유효 접근은** 1~수 사이클 내에 즉시 물리 메모리에 접근하나, **비상주 페이지는** 디스크 I/O를 수반하는 페이지 폴트 핸들러를 거쳐 복구됨

#### 한줄 요약
- MMU가 주소 변환과 권한을 검사하여 유효 시 즉시 접근하고, 부재 시 페이지 폴트 트랩을 발생시켜 OS가 디스크에서 적재한 후 명령어를 재시작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 페이징에서 할당된 고정 페이지의 마지막 여유 공간이 작아 발생하는 메모리 낭비.
- **외부 단편화(External Fragmentation)**: 세그멘테이션에서 가변 블록 할당/해제 반복으로 빈 공간이 조각나 새 세그먼트를 할당하지 못하는 현상.
- **페이지드 세그멘테이션(Paged Segmentation)**: 세그먼트로 논리 분할 후 세그먼트 내부를 다시 고정 크기 페이지로 쪼개어 외부 단편화를 제거한 방식.

</details>

| 비교 항목 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 페이지드 세그멘테이션 |
|:---|:---|:---|:---|
| 분할 단위 | **고정 크기 블록 (4KB, 2MB, 1GB)** | **가변 크기 논리 단위 (코드, 데이터, 스택)** | **가변 세그먼트 내부를 고정 페이지로 분할** |
| 주소 구조 | 1차원 주소 (VPN + Offset) | 2차원 주소 (Segment Selector + Offset) | 2차원 논리 주소 ➔ 1차원 페이징 변환 |
| 단편화 문제 | **내부 단편화 발생, 외부 단편화 0%** | **외부 단편화 발생, 내부 단편화 0%** | **내부 단편화만 일부 발생 (외부 단편화 해결)** |
| 하드웨어 구현 | **MMU 다단계 페이지 테이블 및 TLB** | **세그먼트 테이블 (Base/Limit 비교기)** | 세그먼트 유닛 + 페이징 유닛 2단계 |
| 현대 채택 여부 | **모든 현대 OS 및 프로세서의 표준 채택** | 64비트 x86_64에서 사실상 Flat 모드로 비활성화 | 가상화(EPT) 및 특수 보안 시스템 일부 적용 |

#### 한줄 요약
- 페이징은 외부 단편화를 완벽히 해결하여 현대 시스템의 표준이 되었으며, 세그멘테이션의 논리 보호 개념은 페이지 권한 비트로 흡수되었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: fork 시 메모리를 복제하지 않고 읽기 전용으로 공유하다가, 쓰기 발생 시에만 해당 페이지만 독립 복제하는 기법.
- **쓰레싱(Thrashing)**: 메모리 부족으로 CPU 연산 시간보다 페이지 교체 입출력에 대부분의 시간을 소모하여 시스템이 마비되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다중 프로세스의 메모리 부족으로 인한 **쓰레싱(Thrashing)** 발생 | **워킹셋(Working Set) 모델 및 PFF(Page Fault Frequency)** 제어 | 프로세스별 최소 프레임 보장 및 페이지 폴트 폭증 차단 |
| 프로세스 생성(fork) 시 전체 메모리 물리 복사 오버헤드 | **쓰기 시점 복사(Copy-on-Write, CoW)** 적용 | 자식 프로세스 생성 시간 단축 및 메모리 점유 극소화 |
| 대용량 메모리(DB, JVM) 환경에서 4KB 페이징에 따른 TLB 미스 폭증 | **대형 페이지(Huge Page: 2MB/1GB)** 활성화 | TLB 커버리지 확장 및 주소 변환 오버헤드 90% 절감 |

#### 한줄 요약
- 실무에서는 쓰레싱 방지를 위한 워킹셋 관리, 빠른 생성을 위한 CoW, TLB 미스 방지를 위한 대형 페이지 적용이 핵심이다.

## Ⅶ. 결론

- 대규모 다중 프로세스 환경의 메모리 효율성과 격리를 위해 **고정 크기 블록 기반의 다단계 페이징(Paging) 아키텍처를 표준 채택**하고, 대용량 인메모리 워크로드에는 **대형 페이지(Huge Page)와 CoW 최적화**를 적용하며, 프로세스 생성 및 동시성 제어 시 **워킹셋 기반 프레임 할당 정책**을 확립하는 가상 메모리 시스템 구축

#### 한줄 요약
- 가상 메모리는 현대 OS와 하드웨어의 핵심 기반이며, 페이징 아키텍처와 대형 페이지의 결합이 고성능 메모리 관리의 표준이다.
