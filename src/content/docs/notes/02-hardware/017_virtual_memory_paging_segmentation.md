## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에 실제 물리적 메모리와 무관한 연속적인 논리 주소 공간을 제공하는 하드웨어/OS 관리 기법.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 단위(Page/Frame)로 분할하여 매핑하는 기술.
- **세그멘테이션(Segmentation)**: 코드, 데이터, 스택 등 의미 있는 논리적 가변 크기 단위로 메모리를 분할하여 매핑하는 기술.

</details>

- 정의/개념: 프로세스에 실제 물리 메모리 용량 및 연속성과 무관한 추상화된 주소 공간을 제공하고 고정 크기(Paging) 또는 가변 크기(Segmentation)로 매핑하는 메모리 관리 체계
- 배경/필요성: 물리 메모리 부족 해소, 다중 프로세스 간 메모리 보호 및 **요구 페이징(Demand Paging)을 통한 메모리 적재 효율 극대화**

#### 한줄 요약

- 가상-물리 주소 분리를 통한 **프로세스 메모리 격리 및 요구 페이징 기반 가용성 극대화**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로그램의 모든 페이지를 미리 올리지 않고, 실제 CPU가 참조하는 시점에만 메모리에 적재하는 기법.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 메모리에서는 연속적인 주소가 실제 물리 메모리에서는 분산된 프레임에 적재될 수 있는 특성.

</details>

- 프로세스별 독립적인 **가상 주소 공간** 보장을 통한 프로세스 간 메모리 침범 원천 차단
- 물리 메모리 용량을 초과하는 대용량 프로그램을 **스왑(Swap) 영역**과 연동하여 원활히 구동
- **요구 페이징(Demand Paging)**과 **비연속 물리 프레임 할당**을 통한 물리 메모리 활용률 극대화

#### 한줄 요약

- **독립 가상 주소 공간** 제공과 **요구 페이징(Demand Paging)** 기반 동적 할당

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블(Page Table)**: VPN(가상 페이지 번호)을 PPN(물리 프레임 번호)으로 매핑하는 엔트리(PTE)들의 집합.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 시작 주소(Base), 크기(Limit), 읽기/쓰기/실행 권한을 담은 테이블 항목.

</details>

```text
[ 가상 메모리 관리 아키텍처 ]
┌──────────────────────────────────────────────────────────┐
│ [ 페이징 방식 (Paging) ]                                 │
│  가상 주소 (VPN + Offset) ──> 페이지 테이블 ──> 물리 프레임│
├──────────────────────────────────────────────────────────┤
│ [ 세그멘테이션 방식 (Segmentation) ]                      │
│  가상 주소 (Segment No + Offset) ──> 세그먼트 기술자     │
│                                 ──> Base + Offset 연산   │
└────────────────────────────┬─────────────────────────────┘
                             │
                             ▼
              [ 메모리 관리 장치 (MMU / TLB) ]
                             │
                             ▼
              [ 물리 메모리 (DRAM Physical Frame) ]
```

선의 의미: 페이징(고정 분할)과 세그멘테이션(가변 논리 분할)이 MMU를 거쳐 물리 메모리로 변환되는 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 메모리 관리 장치 (MMU) | 가상 주소를 물리 주소로 실시간 변환 및 보호 권한 검사 수행 |
| 페이지 테이블 (PTE) | 가상 페이지 번호를 고정된 크기의 물리 프레임으로 매핑 |
| 세그먼트 기술자 | 세그먼트의 시작 주소와 크기를 논리적으로 추적 관리 |
| 주기억장치 (DRAM) | 변환된 물리 주소 결과를 기반으로 데이터 적재 및 반환 |

#### 한줄 요약

- **MMU, 페이지 테이블(PTE), 세그먼트 기술자**를 통한 실시간 주소 변환

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령 재시작(Instruction Restart)**: 페이지 폴트 처리 완료 후 중단되었던 CPU 명령어를 처음부터 다시 실행하는 하드웨어 복구 기능.

</details>

```text
[ CPU 가상 주소 메모리 접근 요청 ]
                 │
                 ▼
     [ MMU / TLB 주소 변환 시도 ]
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
 [ 변환 성공 (Valid) ] [ 변환 예외 (Invalid / Non-present) ]
       │                   │
       ▼                   ▼
 [ 물리 주소 데이터 반환 ] [ 비상주 여부 및 접근 권한 검사 ]
                           │
                     ┌─────┴─────┐
                     ▼ [Non-present]   ▼ [권한 위반]
            [ Page Fault 예외 발생 ] [ Segmentation Fault 트랩 ]
                     │
                     ▼
            [ 디스크 Swap-In 적재 ]
                     │
                     ▼
            [ 명령어 재시작 (Restart) ]
```

**동작 원리**

1. **주소 변환 시도**: MMU가 TLB 및 페이지 테이블을 검색하여 가상 주소 변환 시도
2. **적중 시**: 유효한 물리 프레임 주소를 반환하여 1클록 내 데이터 읽기/쓰기 완료
3. **페이지 폴트 발생**: Valid 비트가 0(비상주)일 경우 CPU가 OS 페이지 폴트 핸들러를 트랩 호출
4. **스왑 인 및 재시작**: OS가 보조기억장치에서 빈 프레임으로 페이지를 읽어 올린 뒤 PTE를 갱신하고 **명령어 재시작** 수행

#### 한줄 요약

- 주소 변환 시도 후 **비상주 시 페이지 폴트 트랩을 거쳐 스왑 인 및 명령 재시작**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **내부 단편화 vs 외부 단편화**:
  - 내부 단편화: 고정 페이지 내부의 남는 공간 낭비 (페이징)
  - 외부 단편화: 가변 할당 후 남은 조각 공간들의 총합은 충분하나 연속 공간이 부족해 할당 불가 (세그멘테이션)

</details>

| 메모리 관리 기법 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 페이징 세그멘테이션 (Paged Segmentation) |
|:---|:---|:---|:---|
| 적용 기준 | 현대 범용 OS(Linux, Windows) 및 64비트 CPU 표준 | 모듈별 보호 및 공유가 강조되는 논리 단위 분할 | 세그먼트의 논리적 보호와 페이징의 할당 용이성 절충 |
| 핵심 특징 | 고정 크기(4KB/2MB) 분할, 비연속 물리 프레임 매핑 | 가변 크기(Code/Data/Stack) 분할, 베이스/리밋 레지스터 | 세그먼트를 먼저 정의하고 각 세그먼트 내부를 고정 페이지 분할 |
| 한계 및 위험 | 페이지 내부 낭비인 내부 단편화(Internal Fragmentation) | 메모리 가변 할당에 따른 외부 단편화(External Fragmentation) | 2단계 주소 변환(세그먼트 테이블 $\to$ 페이지 테이블) 오버헤드 |

#### 한줄 요약

- 페이징은 **내부 단편화와 관리 용이성**, 세그멘테이션은 **논리적 보호와 외부 단편화**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Copy-on-Write(CoW)**: `fork()` 시스템 콜 시 부모-자식 프로세스가 메모리 페이지를 공유하다가, 한쪽이 쓰기를 시도할 때만 물리 프레임을 복제하는 최적화.
- **쓰레싱(Thrashing)**: 물리 메모리가 부족하여 프로세스 실행 시간보다 페이지 교체 디스크 I/O 시간이 더 길어지는 시스템 마비 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 인한 잦은 교체와 **쓰레싱**, **주 페이지 폴트** 급증 | 작업 집합 크기 기반의 메모리 할당량 제어 및 컨테이너 확장 | 디스크 입출력 마비 현상 원천 차단 |
| 동일 라이브러리 중복 적재에 따른 메모리 공간 낭비 심화 | **읽기 전용 공유 프레임**을 활용한 프로세스 간 병합 매핑 | 중복 물리 프레임 제거 및 실가용 메모리 절약 |
| 순수 세그멘테이션 도입 시 **외부 단편화**로 인한 배치 한계 돌파 | **페이지 세그멘테이션 혼용** 모델 채택 | 외부 단편화 방지 및 논리적 보안 유지 장점 동시 수용 |
| 다중 프로세스 분기 및 생성 시 메모리 복사 오버헤드 지연 | **쓰기 시점 복사(CoW)** 기법을 적용한 페이지 공간 생성 | 물리적 복사 지연 은닉 및 프로세스 생성 비용 극소화 |

#### 한줄 요약

- **Working Set 제어·Shared Frame·CoW(Copy-on-Write)**로 쓰레싱 및 낭비 방어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상 메모리 아키텍처의 수렴**: x86-64 및 ARMv8/v9 등 현대 64비트 아키텍처는 세그멘테이션을 최소화(Flat Model)하고 다단계 페이징을 표준으로 수렴.

</details>

- 현대 운영체제는 **페이징을 기본 표준으로 채택하고 Copy-on-Write 및 가상 메모리 보호 영역을 유연하게 결합**

#### 한줄 요약

- **고정 크기 페이징 표준 위에 CoW와 보호 메커니즘**을 결합한 최적 가상화 구현
