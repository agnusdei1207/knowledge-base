## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에게 연속된 독자 논리 주소 공간을 제공하여 물리 메모리 용량의 한계를 극복하고, 프로세스 간 메모리 완전 격리 및 비연속 물리 메모리 할당을 실현하는 운영체제-하드웨어 협력 메모리 관리 체계.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 블록(가상 페이지, 물리 프레임)으로 균등 분할하여 외부 단편화 없이 비연속적으로 매핑하는 기법.
- **세그멘테이션(Segmentation)**: 프로그램의 논리적 모듈 단위(코드, 데이터, 스택, 힙)에 따라 가변 크기의 세그먼트로 메모리를 분할하고 논리적 보호와 공유를 제어하는 기법.

</details>

- 정의/개념: 물리 메모리 한계를 극복하고 프로세스 간 메모리를 보호하기 위해 고정 크기 블록으로 사상하는 **페이징**과 논리 모듈 단위로 분할하는 **세그멘테이션**으로 구성된 가상 메모리 관리 아키텍처
- 배경/필요성: 물리 메모리 직접 연속 할당 방식의 심각한 **외부 단편화** 및 프로세스 간 메모리 침범 결함을 해소하고 물리 DRAM 용량을 초과하는 대규모 프로세스 실행 지원 필요

#### 한줄 요약
- 가상 메모리는 물리 배치로부터 프로세스를 분리하여 비연속 할당, 메모리 보호, 용량 확장을 실현하는 핵심 시스템 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 프로그램 실행 시 전체를 미리 메모리에 적재하지 않고, 실제 접근이 발생하여 페이지 폴트가 일어날 때만 해당 페이지를 물리 메모리로 적재하는 기법.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소 공간상에서 연속된 페이지들을 물리 메모리의 임의의 빈 물리 프레임에 흩어져 배치하는 방식.
- **메모리 보호(Memory Protection)**: 페이지 테이블이나 세그먼트 기술자에 읽기(R), 쓰기(W), 실행(X) 권한 비트를 설정하여 불법 접근을 하드웨어적으로 차단하는 보안 기능.

</details>

- **요구 페이징** 기반 필요 페이지만 메모리에 적재하여 물리 메모리 활용 극대화
- **비연속 할당**을 통해 물리 메모리의 분산 프레임들을 단일 연속 가상 공간으로 투명 제공
- 페이지 테이블 엔트리(PTE)의 **메모리 보호** 비트(R/W/X) 기반 프로세스 간 메모리 침범 원천 차단

#### 한줄 요약
- 페이징은 외부 단편화를 없애고 배치를 단순화하며, 세그멘테이션은 프로그램 논리 구조에 맞춘 정밀한 권한 보호와 공유를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 내부에 위치하여 가상 주소를 물리 주소로 실시간 변환하고 권한 위반을 검사하는 하드웨어 유닛.
- **페이지 테이블(Page Table)**: 가상 페이지 번호(VPN)를 물리 프레임 번호(PPN) 및 접근 제어 비트와 매핑하여 DRAM에 상주하는 OS 커널 정본 테이블.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 물리 기준 시작 주소(Base), 크기 한계(Limit), 접근 권한(R/W/X)을 정의하는 디스크립터 구조체.

</details>

```text
+-----------------------------------------------------------------------+
| 가상 메모리 시스템 하드웨어 및 소프트웨어 아키텍처                   |
|                                                                       |
|  [프로세스 가상 주소 공간 (Virtual Address Space)]                    |
|         │                                                             |
|  +------v----------------------------------------------------------+  |
|  | 메모리 관리 장치 (MMU: Memory Management Unit)                   |  |
|  |  +-----------------------------------------------------------+  |  |
|  |  | 세그멘테이션 유닛: 세그먼트 레지스터, Base/Limit 한계 검증   |  |  |
|  |  +-----------------------------+-----------------------------+  |  |
|  |                                | 선형 주소 생성                |  |
|  |  +-----------------------------v-----------------------------+  |  |
|  |  | 페이징 유닛: TLB 고속 주소 캐시 + 다단계 페이지 테이블 워커 |  |  |
|  |  +-----------------------------+-----------------------------+  |  |
|  +--------------------------------|--------------------------------+  |
|                                   | 물리 주소 (Physical Address)      |
|  +--------------------------------v--------------------------------+  |
|  | 물리 주기억장치 (Main Memory: DRAM)                             |  |
|  |  - 페이지 테이블 엔트리 (PTE) 및 물리 프레임 (Physical Frames)  |  |
|  +--------------------------------+--------------------------------+  |
|                                   | 스왑 페이지 인출 (I/O 트랜잭션)   |
|  +--------------------------------v--------------------------------+  |
|  | 보조기억장치 (SSD / HDD: Swap Area & Page File)                 |  |
+--+-----------------------------------------------------------------+--+
```

선의 의미: `+---+`는 가상 메모리 계층 및 장치 경계, `->`는 단계별 주소 변환 및 페이지 폴트 스왑 경로

| 구성요소 | 책임 |
|:---|:---|
| MMU | 가상 주소의 물리 주소 변환 및 페이지별 하드웨어 **접근 권한 검증** |
| 세그먼트 테이블 | 논리 세그먼트별 **기준 주소(Base) 및 한계(Limit)** 경계 정보 보관 |
| 다단계 페이지 테이블 | 가상 페이지와 물리 프레임 간의 **VPN-PPN 매핑**과 상태 비트 보관 |
| 물리 프레임 | 프로세스 실행 코드 및 런타임 데이터가 실제로 상주하는 물리 블록 |

#### 한줄 요약
- 가상 메모리는 CPU 내부 MMU(TLB, 워커)와 DRAM 상의 페이지/세그먼트 테이블이 협력하여 물리 프레임으로의 투명한 주소 변환을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: CPU가 접근하려는 페이지가 물리 메모리에 적재되어 있지 않거나(Present=0) 권한을 위반했을 때 발생하는 하드웨어 트랩 예외.
- **명령어 재시작(Instruction Restart)**: OS가 페이지 폴트를 처리하여 디스크에서 물리 프레임으로 적재 완료한 후, 중단되었던 CPU 명령어를 처음부터 온전히 재실행하는 복구 메커니즘.

</details>

```text
[CPU 가상 주소 접근 (VPN + Offset)]
               │
               ▼
      1. 주소 변환 및 권한 검사
   ┌───────────┴───────────┐
(유효 매핑 및 권한 일치) (부재 또는 권한 위반)
   │                       │
   ▼                       ├─ 권한 위반: 세그멘테이션 폴트(SIGSEGV) 프로세스 종료
2. 물리 주소 도출 및 접근  │
   │                       └─ 페이지 부재:
   ▼                          3. 페이지 폴트 트랩 발생
[DRAM 데이터 즉시 반환]               │
                                      ▼
                               4. 디스크 스왑 페이지 적재
                                      │
                                      ▼
                               5. 매핑 갱신 및 명령어 재시작
```

분기 결과: **유효 접근**은 수 사이클 내 즉시 완료, **비상주 페이지**는 디스크 I/O를 수반하는 페이지 폴트 핸들러를 통해 적재 복구

**동작 원리**

1. **주소 변환 및 권한 검사**: CPU가 가상 주소 접근 시 MMU가 TLB 및 페이지 테이블을 조회하여 해당 페이지의 매핑 및 R/W/X 권한을 검사함
2. **물리 주소 도출 및 접근**: 페이지가 물리 메모리에 유효하고 권한을 만족할 경우 PPN과 오프셋을 결합하여 DRAM 물리 주소로 즉시 접근함
3. **페이지 폴트 트랩 발생**: 대상 페이지의 유효 비트가 0(부재)이거나 보호 권한 위반 시 하드웨어 트랩을 발생시켜 OS 커널 페이지 폴트 핸들러를 호출함
4. **디스크 스왑 페이지 적재**: OS가 보조기억장치 스왑 영역에서 해당 페이지를 물리 메모리의 빈 프레임으로 인출하고 페이지 테이블 엔트리를 갱신함
5. **매핑 갱신 및 명령어 재시작**: TLB 엔트리를 리필하고 중단되었던 CPU 명령어를 처음부터 온전히 재실행함

#### 한줄 요약
- MMU가 주소 변환과 권한을 검사하여 유효 시 즉시 접근하고, 부재 시 페이지 폴트 트랩을 발생시켜 OS가 디스크에서 적재한 후 명령어를 재시작한다.

## Ⅴ. 종류 및 비교

| 가상 메모리 기법 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 페이지드 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | **외부 단편화 제거** 및 균등 메모리 관리 | **논리적 모듈 보호** 및 코드/데이터 공유 | **논리 모듈화와 외부단편화 제거** 절충 |
| 분할 단위 | **고정 크기 블록**(4KB, 2MB, 1GB) | **가변 논리 단위**(코드, 데이터, 스택) | **가변 세그먼트** 내 고정 페이지 분할 |
| 주소 구조 | 1차원 주소 (VPN + Offset) | 2차원 주소 (Segment Selector + Offset) | 2차원 논리 주소 ➔ 1차원 페이징 변환 |
| 단편화 영향 | **내부 단편화** 발생 (외부 단편화 0%) | **외부 단편화** 발생 (내부 단편화 0%) | **내부 단편화** 일부 발생 (외부 단편화 제거) |
| 현대 채택 여부 | **현대 범용 OS 표준** 채택 | 64비트 아키텍처에서 Flat 모드로 비활성화 | 가상화 하이퍼바이저 및 보안 컨테이너 |

#### 한줄 요약
- 페이징은 외부 단편화를 완벽히 해결하여 현대 시스템의 표준이 되었으며, 세그멘테이션의 논리 보호 개념은 페이지 권한 비트로 흡수되었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: fork 시 메모리를 복제하지 않고 읽기 전용으로 공유하다가, 쓰기 발생 시에만 해당 페이지만 독립 복제하는 기법.
- **쓰레싱(Thrashing)**: 메모리 부족으로 CPU 연산 시간보다 페이지 교체 입출력에 대부분의 시간을 소모하여 시스템이 마비되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다중 프로세스 메모리 부족에 따른 **쓰레싱** 현상 발생 | **워킹셋(Working Set)** 모델 및 PFF 기반 프레임 제어 | 프로세스별 최소 프레임 보장 및 페이지 폴트 폭증 차단 |
| 프로세스 fork 시 메모리 전체 물리 복사 오버헤드 | **쓰기 시점 복사** 기법 적용 | 자식 프로세스 생성 지연 단축 및 물리 메모리 점유 최소화 |
| 대용량 메모리 환경에서 4KB 페이징의 TLB 미스 폭증 | 2MB/1GB 단위 **대형 페이지** 활성화 | TLB 도달 범위 확장 및 주소 변환 지연 대폭 절감 |

#### 한줄 요약
- 실무에서는 쓰레싱 방지를 위한 워킹셋 관리, 빠른 생성을 위한 CoW, TLB 미스 방지를 위한 대형 페이지 적용이 핵심이다.

## Ⅶ. 결론

- 현대 운영체제와 64비트 마이크로프로세서는 외부 단편화를 근본 해결한 **다단계 페이징(4단계/5단계 Paging)**을 지배적 표준으로 채택하였으며, 최근 대규모 AI 추론 및 컨테이너 가상화 인프라에서는 메모리 접근 지연을 줄이기 위해 **투명한 대형 페이지(THP)와 하드웨어 보조 가상화(EPT/NPT)**로 진화 중이므로, 시스템 설계 및 커널 튜닝 시 워크로드 메모리 크기와 스왑 빈도를 고려하여 페이지 교체 알고리즘과 워킹셋 할당 정책을 결정해야 함

#### 한줄 요약
- 가상 메모리는 현대 OS와 하드웨어의 핵심 기반이며, 페이징 아키텍처와 대형 페이지의 결합이 고성능 메모리 관리의 표준이다.
