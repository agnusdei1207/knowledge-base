## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에 물리 메모리와 분리된 논리 주소 공간을 제공해 비연속 배치와 프로세스 격리를 가능하게 하는 메모리 관리 기법.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 페이지·프레임 단위로 나누어 비연속 매핑하는 방식.
- **세그멘테이션(Segmentation)**: 코드·데이터·스택 같은 논리 단위를 가변 크기 세그먼트로 관리해 의미 단위 보호·공유를 지원하는 방식.

</details>

- 정의/개념: 프로세스별 가상 주소를 **페이징** 또는 **세그멘테이션**으로 물리 메모리에 매핑하는 메모리 관리 체계
- 배경/필요성: 연속 물리 할당만으로는 흩어진 빈 공간을 모을 수 없어, 물리 메모리보다 큰 주소 공간도 프로세스 간 격리도 제공 불가

#### 한줄 요약
- **가상 메모리**가 제공하는 것은 큰 공간이 아니라 물리 배치로부터의 독립이며, 용량 확장은 그 독립성에서 파생된 부수 효과에 가깝다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 실제 참조가 발생한 시점에만 해당 페이지를 물리 메모리에 적재하는 방식; 초기 적재 비용 감소.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소상 연속된 페이지를 서로 다른 물리 프레임에 배치해 단편화 없이 메모리 사용.
- **메모리 보호(Memory Protection)**: 페이지·세그먼트별 읽기·쓰기·실행 권한으로 허가되지 않은 접근을 차단하는 기능.

</details>

- **요구 페이징**으로 참조 전 페이지를 적재하지 않아 초기 메모리 사용량 감소
- **비연속 할당**으로 물리 메모리의 분산 프레임을 연속 가상 공간으로 투명하게 제공
- 페이지·세그먼트별 **메모리 보호**로 프로세스 간 불법 접근 차단

#### 한줄 요약
- **요구 페이징**과 **메모리 보호**는 같은 변환 표를 공유하므로, 성능 기법과 보안 기법이 한 자료구조에 얹혀 있다는 점이 이 설계의 강점이자 공격 표면이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블(Page Table)**: 가상 페이지 번호를 물리 프레임 번호와 접근 권한으로 변환하는 엔트리 집합.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 기준 주소·크기·접근 권한을 기록한 디스크립터 항목.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 접근 권한 검사를 하드웨어로 수행하는 장치.

</details>

```text
[가상 메모리 관리]
├─ MMU
│  ├─ 페이징 변환 (페이지 테이블)
│  ├─ 세그멘테이션 변환 (세그먼트 기술자)
│  └─ 결합 변환 (세그먼트 선택 후 페이지 변환)
└─ 물리 프레임
```

선의 의미: 가지(`├─`)는 MMU가 지원하는 대안·결합 변환 구조와 물리 저장 대상

| 구성요소 | 책임 |
|:---|:---|
| **MMU** | 가상→물리 주소 변환·접근 권한 검사 |
| 페이지 테이블 | 가상 페이지 번호·물리 프레임 번호·권한 매핑 |
| 세그먼트 기술자 | 논리 세그먼트의 기준 주소·크기·권한 관리 |
| 물리 프레임 | 변환된 실제 데이터·코드 저장 |

#### 한줄 요약
- **세그먼트 기술자**는 프로그램의 의미 단위를 알고 **페이지 테이블**은 모르므로, 보호를 정교하게 하려면 전자가 유리하고 배치를 단순하게 하려면 후자가 유리하다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: 페이지가 비상주하거나 접근 권한 오류로 OS 예외 처리가 필요한 상황.
- **명령어 재시작(Instruction Restart)**: 예외 처리가 끝난 뒤 중단한 명령어를 처음부터 다시 실행하는 처리.

</details>

```text
CPU 가상 주소 접근
      │
      ▼
1. MMU 변환 및 권한 확인
      │
      ├─ 권한 위반 ─────────→ 접근 예외 처리
      ├─ 상주·권한 허용 ────→ 물리 메모리 접근
      └─ 비상주 ────────────→ 2. 페이지 폴트 및 페이지 적재
                                         │
                                   3. 명령어 재시작
```

분기 결과: 권한 위반은 프로그램 오류로 확정되어 되돌릴 수 없지만, 비상주는 정상 동작이라 **페이지 폴트** 처리 후 **명령어 재시작**으로 아무 일 없던 것처럼 재개

#### 한줄 요약
- 명령어를 도중에 이어 하지 않고 처음부터 다시 실행한다는 규칙이 가상 메모리를 성립시키며, 이 때문에 명령어는 중간 부작용을 남기지 않도록 설계돼야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 고정 크기 페이지에서 실제로 쓰지 않는 뒷부분이 그대로 낭비되는 현상으로, 낭비량의 상한이 페이지 크기로 미리 정해짐.
- **외부 단편화(External Fragmentation)**: 가변 크기 할당이 반복되며 빈 공간이 잘게 흩어져, 총량은 충분한데도 연속 배치가 불가능해지는 현상.
- **페이지 세그멘테이션(Paged Segmentation)**: 세그먼트로 논리 구획을 나눈 뒤 각 세그먼트 내부를 다시 페이지로 매핑해, 논리 보호와 고정 배치를 함께 얻는 결합 방식.

</details>

| 메모리 관리 방식 | 페이징 | 세그멘테이션 | 페이지 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | 고정 단위·비연속 배치 우선 | 논리 단위 보호·공유 우선 | 논리 구분과 고정 배치 동시 필요 |
| 핵심 특징 | 고정 크기 페이지·프레임의 **비연속 할당** | 가변 세그먼트를 기준·한계 레지스터로 관리 | 세그먼트 내부에 페이지 테이블을 한 단 추가 |
| 한계 | **내부 단편화**와 페이지 테이블 메모리 비용 | **외부 단편화**와 가변 배치 관리 복잡도 | 변환 단계 증가로 지연·관리 부담 상승 |

#### 한줄 요약
- 페이징이 이긴 이유는 보호가 더 나아서가 아니라 단편화를 **내부 단편화**라는 예측 가능한 형태로 바꿨기 때문이며, 예측 가능성이 곧 관리 가능성이었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: 공유 페이지에 쓰기가 발생할 때만 별도 물리 페이지를 복사하는 방식.
- **쓰레싱(Thrashing)**: 페이지 교체 입출력이 실제 실행 시간보다 많아져 시스템이 심하게 느려지는 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 **쓰레싱** 발생 | 작업 집합 기준 프레임 배분·동시 실행량 조절 | 페이지 입출력 폭증 완화 |
| 큰 페이지가 **내부 단편화** 유발 | 연속 접근 영역에만 대형 페이지 선택 적용 | 커버리지·공간 효율 균형 |
| 프로세스 생성 시 전체 메모리 복사 비용 | **CoW** 기반 페이지 공유 | 초기 생성 시간·메모리 사용 감소 |
| 세그멘테이션 가변 배치의 **외부 단편화** | 페이징 결합·물리 프레임 연속성 보장 | 배치 실패·관리 부담 완화 |

#### 한줄 요약
- **쓰레싱**만은 다른 셋과 성격이 달라 국소적 조정으로 해결되지 않으며, 동시 실행량을 줄이는 것 말고는 물러설 방법이 없다.

## Ⅶ. 결론

- 현대 범용 시스템은 **페이징**을 기본으로 하고 페이지 권한으로 보호하며, 세그멘테이션은 논리 구획을 하드웨어 주소 변환에 반영해야 하는 호환·특수 환경에 한정

#### 한줄 요약
- **세그멘테이션**이 주소 변환에서 밀려난 뒤에도 논리 구획 개념 자체는 페이지 권한 비트로 살아남았으므로, 사라진 것은 개념이 아니라 구현 방식이다.
