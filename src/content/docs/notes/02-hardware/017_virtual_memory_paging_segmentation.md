## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에 물리 메모리와 분리된 논리 주소 공간을 제공하는 메모리 관리 기법입니다.
- **페이징(Paging)**: 가상 공간과 물리 메모리를 고정 크기 페이지·프레임으로 나누어 매핑하는 방식입니다.
- **세그멘테이션(Segmentation)**: 코드·데이터·스택 같은 논리 단위를 가변 크기 세그먼트로 관리하는 방식입니다.

</details>

- 정의/개념: 가상 주소를 페이징·세그멘테이션으로 물리 주소에 매핑하는 **메모리 추상화 체계**
- 배경/필요성: 프로세스 격리와 물리 메모리의 비연속 배치 지원

#### 한줄 요약

- 프로그램은 연속된 큰 공간을 쓰는 것처럼 보지만, 운영체제는 실제 메모리의 여러 위치에 나누어 배치할 수 있습니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 실제 참조가 발생한 페이지를 그 시점에 물리 메모리에 적재하는 방식입니다.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소상 연속된 페이지를 서로 다른 물리 프레임에 배치하는 방식입니다.
- **메모리 보호(Memory Protection)**: 프로세스별 읽기·쓰기·실행 권한으로 허가되지 않은 접근을 막는 기능입니다.

</details>

- 요구 시 적재하는 **요구 페이징**
- 물리 프레임을 나누어 쓰는 **비연속 할당**
- 주소 공간별 **메모리 보호**

#### 한줄 요약

- 필요한 부분만 물리 메모리에 올리고 서로 다른 프로세스의 주소를 분리하므로, 작은 메모리로도 큰 공간과 안전한 격리를 제공할 수 있습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블(Page Table)**: 가상 페이지 번호를 물리 프레임 번호와 권한으로 변환하는 엔트리 집합입니다.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 기준 주소, 크기, 접근 권한을 기록한 항목입니다.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 접근 권한 검사를 수행하는 하드웨어입니다.

</details>

```text
[가상 메모리 관리]
├─ MMU
├─ 페이징
│  └─ 페이지 테이블
├─ 세그멘테이션
│  └─ 세그먼트 기술자
└─ 물리 프레임
```

| 구성요소 | 책임 |
|:---|:---|
| MMU | 가상 주소 변환과 권한 검사 |
| 페이지 테이블 | 가상 페이지·물리 프레임 매핑 |
| 세그먼트 기술자 | 논리 세그먼트의 기준·크기·권한 관리 |
| 물리 프레임 | 변환된 데이터와 코드를 실제 저장 |

#### 한줄 요약

- MMU가 주소를 해석하고, 페이징 표와 세그먼트 기술자가 각각 고정 단위와 논리 단위의 배치 정보를 제공합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: 페이지가 비상주하거나 접근 권한이 맞지 않아 운영체제 처리가 필요한 예외입니다.
- **명령어 재시작(Instruction Restart)**: 예외 처리가 끝난 뒤 중단한 명령어를 다시 실행하는 처리입니다.

</details>

```text
[1. 가상 주소 접근]
          │
          ▼
[2. MMU 변환·권한 확인]
          │
          ├─ 성공 → [3. 물리 메모리 접근]
          │
          └─ 비상주 → [3. 페이지 폴트 처리]
                           │
                           ▼
                     [4. 페이지 적재·명령어 재시작]
```

동작 원리:

1. 가상 주소 접근: CPU가 프로세스 주소 공간을 참조
2. MMU 변환·권한 확인: 페이지 또는 세그먼트 매핑과 접근 권한 판정
3. 물리 메모리 접근 또는 페이지 폴트 처리: 유효하면 접근하고 비상주면 OS 호출
4. 페이지 적재·명령어 재시작: 필요한 페이지를 준비하고 중단 명령어 재개

#### 한줄 요약

- 주소가 정상적으로 연결되어 있으면 바로 접근하고, 메모리에 없는 페이지면 운영체제가 자리를 마련한 뒤 같은 명령어를 다시 진행합니다.

## Ⅴ. 종류 및 비교

| 메모리 관리 방식 | 페이징 | 세그멘테이션 | 페이지 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | 고정 단위와 비연속 배치 우선 | 논리 단위 보호·공유 우선 | 논리 구분과 고정 배치 동시 필요 |
| 핵심 특징 | 페이지·프레임 매핑 | 가변 세그먼트와 기준·한계 | 세그먼트 내부의 페이지 매핑 |
| 한계 | 내부 단편화와 페이지 테이블 비용 | 외부 단편화와 가변 할당 비용 | 변환 단계와 관리 복잡도 증가 |

#### 한줄 요약

- 페이징은 관리와 배치가 단순하고 세그멘테이션은 의미별 보호가 쉽지만, 둘을 결합하면 두 단계 변환 비용이 생깁니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: 공유 페이지에 쓰기가 발생할 때만 별도 물리 페이지를 복사하는 방식입니다.
- **쓰레싱(Thrashing)**: 페이지 교체 입출력이 실행보다 많아져 시스템이 심하게 느려지는 상태입니다.
- **내부 단편화(Internal Fragmentation)**: 할당 단위 내부의 남는 공간이 낭비되는 현상입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 쓰레싱 증가 | 작업 집합 기준 프레임 배분과 동시 실행량 조절 | 페이지 입출력 폭증 완화 |
| 큰 페이지가 내부 단편화 유발 | 연속 접근 영역에만 대형 페이지 적용 | 커버리지와 공간 효율 균형 |
| 프로세스 생성 때 전체 메모리 복사 | CoW 기반 페이지 공유 | 초기 생성 시간과 메모리 사용 감소 |
| 세그멘테이션 가변 배치의 외부 단편화 | 페이징 결합과 물리 프레임 관리 | 배치 실패와 관리 부담 완화 |

#### 한줄 요약

- 가상 메모리는 주소 변환만의 문제가 아니라, 페이지 크기와 프레임 배분, 복사 시점까지 함께 조절해야 실제 성능이 유지됩니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **작업 집합(Working Set)**: 일정 시간 동안 프로세스가 반복 참조하는 메모리 페이지들의 집합입니다.

</details>

- 범용 운영체제는 **작업 집합**과 보호 요구를 기준으로 페이징을 우선하고, 논리 단위 보호가 핵심이면 세그멘테이션 또는 결합 방식을 선택

#### 한줄 요약

- 현대 시스템에서는 고정 페이지의 관리 이점을 기본으로 삼되, 프로그램의 보호 단위와 메모리 압박에 맞춰 페이지 크기와 적재 정책을 조정합니다.
