## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에 실제 물리적 용량과 무관한 연속적인 추상화 주소 공간을 제공하는 하드웨어 및 운영체제 관리 체계이다.
- **물리 프레임(Physical Frame)**: 주기억장치를 페이지와 동일한 고정 크기 블록으로 분할하여 데이터를 배치하는 단위이다.
- **페이징(Paging)**: 가상 주소 공간과 물리 공간을 고정 크기의 페이지 및 프레임으로 분할 매핑하는 기술이다.
- **세그멘테이션(Segmentation)**: 코드, 데이터 등 논리적 블록 단위인 가변 크기로 메모리를 분할하여 매핑하는 기술이다.

</details>

- 정의: 프로세스에 논리적 연속 공간을 제공하고 **페이징**과 **세그멘테이션** 방식으로 관리하는 **가상 메모리** 체계
- 배경: 다중 프로세스의 동시 적재 불가 한계를 극복하고 물리 메모리 침범을 방지하기 위함

#### 한줄 요약

- 가상 주소와 물리 주소를 분리하여 프로세스를 격리하고 요구 적재 기반의 메모리 관리를 지원하는 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 주소 공간(Virtual Address Space)**: 각 독립 프로세스가 타 프로세스와의 충돌 없이 독점 참조할 수 있는 논리적 연속 주소 영역이다.
- **요구 페이징(Demand Paging)**: 프로그램 실행에 필요한 페이지 데이터만 참조 시점에 보조기억장치에서 인출하는 기술이다.
- **비상주 페이지(Non-Resident Page)**: 가상 공간에는 할당되었으나 실제 물리 메모리에 들어있지 않은 페이지 상태이다.
- **보조기억장치(Secondary Storage)**: 비상주 익명 페이지나 파일 데이터를 보관하는 디스크 기반 스왑 저장장치이다.

</details>

- 프로세스별로 독립적인 **가상 주소 공간**을 보장하여 무단 접근을 차단함.
- 물리 메모리를 초과하는 주소를 **비상주 페이지**로 전환하여 스왑 영역에 보관함.
- **요구 페이징** 기법을 통해 실제 참조 시점에만 프레임을 동적으로 할당함.

#### 한줄 요약

- 주소 공간의 논리적 분리를 통해 접근 보호를 달성하고, 참조 기반 적재를 통해 메모리 활용도를 최적화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit)**: 가상 주소를 메타데이터를 참조하여 물리 주소로 실시간 변환하는 하드웨어 블록이다.
- **변환 색인 버퍼(Translation Lookaside Buffer)**: 주소 변환 결과를 캐싱하여 변환 시간을 획기적으로 가속하는 전용 버퍼이다.
- **페이지 테이블 항목(Page Table Entry)**: 물리 번호, 유효 비트, 권한 정보가 담긴 배열 단위이다.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트 시작 물리 주소와 크기, 권한이 담긴 서술자 표이다.
- **물리 페이지 번호(Physical Page Number)**: 변환 완료 시 도출되는 메인 메모리 내 프레임의 고유 번호이다.
- **페이지 테이블(Page Table)**: 가상 페이지 번호를 물리 페이지 번호로 매핑한 메모리 내부의 디렉터리 배열이다.

</details>

```text
[ 가상 메모리 관리 아키텍처 ]
+------------------------------------------------------+
| [ 페이징 방식 ]                                      |
| 가상 페이지 번호 ──> 페이지 테이블 ──> 물리 프레임   |
+------------------------------------------------------+
| [ 세그멘테이션 방식 ]                                |
| 세그먼트 선택자 ──> 세그먼트 기술자 ──> 베이스 주소  |
+------------------------------------------------------+
                           │
                           ▼
                 [ 메모리 관리 장치 ]
```

| 구성요소 | 책임 |
|:---|:---|
| **메모리 관리 장치** | 가상 주소를 물리 주소로 실시간 변환 및 보호 권한 검사 수행 |
| **페이지 테이블** | 가상 페이지 번호를 고정된 크기의 물리 프레임으로 매핑 |
| **세그먼트 기술자** | 세그먼트의 시작 주소와 크기를 논리적으로 추적 관리 |
| 주기억장치 | 변환된 물리 주소 결과를 기반으로 데이터 적재 및 반환 |

#### 한줄 요약

- 메모리 관리 장치가 페이지 테이블과 세그먼트 기술자를 참조하여 가상 주소를 유효한 물리 주소로 변환한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: 참조하려는 페이지가 메모리에 상주하지 않아 운영체제가 보조기억장치에서 적재하는 예외이다.
- **명령 재시작(Instruction Restart)**: 페이지 적재 수습 완료 후 중단되었던 기계어 접근 명령을 다시 구동하는 처리 방식이다.
- **가상 페이지 번호(Virtual Page Number)**: 가상 주소에서 페이지 테이블 인덱싱에 사용되는 상위 비트이다.
- **접근 예외(Access Exception)**: 지정된 크기를 초과하거나 읽기 구역에 쓰기를 시도할 때 발생하는 보안 하드웨어 트랩이다.

</details>

```text
[ 가상 주소 메모리 접근 요청 발생 ]
           │
           ▼
[ 가상 페이지 번호 기반 테이블 변환 시도 ]
           │
     ┌─────┴─────┐
     ▼           ▼
[ 변환 성공 ] [ 예외 조건 검출 ]
     │           │
     ▼           ▼
[ 물리 주소 반환 ] [ 비상주 여부 및 권한 판별 ]
                 │
           ┌─────┴─────┐
           ▼           ▼
  [ 페이지 폴트 발생 ] [ 무효 접근 예외 발생 ]
           │
           ▼
  [ 저장장치 교체 및 적재 ]
           │
           ▼
    [ 명령 재시작 수행 ]
```

### 동작 원리

1. 가상 주소 변환: **가상 페이지 번호**를 기반으로 물리 주소 매핑과 접근 권한을 검사함.
2. 페이지 폴트 처리: 비상주 상태 시 **페이지 폴트** 예외를 통해 스왑 영역에서 데이터를 물리 프레임에 적재함.
3. 오류 차단: 메모리 접근 위반 시 **접근 예외**를 발생시켜 프로세스를 보호함.
4. 명령 재시작: 복구 가능한 폴트 처리가 끝나면 중단된 상태를 복원하고 **명령 재시작**을 수행함.

#### 한줄 요약

- 메모리 관리 장치에서 변환을 시도하며, 상주하지 않을 경우 운영체제의 페이지 폴트 처리 후 명령을 다시 시작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 고정 페이지 할당 시 프로그램 데이터가 적어 남아버리는 낭비 공간이다.
- **외부 단편화(External Fragmentation)**: 가변 구역의 반복 할당으로 전체 여유 공간은 충분하나 연속된 구역이 없어 적재하지 못하는 현상이다.
- **비연속 프레임 배치(Non-Contiguous Allocation)**: 가상 주소 상으로는 연속된 공간이 실제 메모리에서는 완전히 비연속적인 프레임들에 나뉘어 적재되는 성질이다.

</details>

| 비교 항목 | 페이징 방식 | 세그멘테이션 방식 |
|:---|:---|:---|
| 분할 단위 | 고정 크기의 논리 페이지 및 물리 프레임 단위 | 코드나 스택 등 논리적 가변 크기의 세그먼트 단위 |
| 메모리 배치 | **비연속 프레임 배치** 구조 적용 | 단일 논리 세그먼트 내의 연속 메모리 배치 필수 적용 |
| 주소 구조 | **가상 페이지 번호**와 오프셋의 결합 형태 | 세그먼트 선택자와 오프셋의 결합 형태 |
| 단편화 문제 | 고정 크기에 따른 **내부 단편화** 현상 발생 | 가변적 할당에 따른 **외부 단편화** 부작용 심화 |
| 실무 적용 | 현대 범용 운영체제 및 중앙처리장치의 표준 아키텍처 | 공유와 보호 측면에 유리하나 현대 구조에선 혼용 또는 배제됨 |

#### 한줄 요약

- 페이징은 내부 단편화가 존재하지만 고정 크기 배치가 쉬워 현대 표준으로 쓰이고, 세그멘테이션은 논리 단위 관리에 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰레싱(Thrashing)**: 물리 프레임이 부족해 연산보다 페이지 교체 입출력이 반복되는 교착 상태이다.
- **주 페이지 폴트(Major Page Fault)**: 디스크 입출력이 실제로 수반되어 극심한 시스템 지연을 유발하는 현상이다.
- **부 페이지 폴트(Minor Page Fault)**: 이미 다른 프로세스에 의해 로드되어 디스크 접근 없이 매핑만 연결하는 현상이다.
- **읽기 전용 공유 프레임(Read-Only Shared Frame)**: 공유 라이브러리를 여러 프로세스가 단일 물리 프레임에 매핑하여 절약하는 기법이다.
- **페이지 세그멘테이션 혼용(Paged Segmentation)**: 논리 세그먼트 내부를 다시 고정 페이지로 나누어 외부 단편화를 차단하는 하이브리드 기법이다.
- **쓰기 시점 복사(Copy-on-Write)**: 프로세스 생성 시 주소 공간을 우선 공유하다가 실제 쓰기 연산 시 물리 프레임을 복제하는 최적화 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 인한 잦은 교체와 **쓰레싱**, **주 페이지 폴트** 급증 | 작업 집합 크기 기반의 메모리 할당량 제어 및 컨테이너 확장 | 디스크 입출력 마비 현상 원천 차단 |
| 동일 라이브러리 중복 적재에 따른 메모리 공간 낭비 심화 | **읽기 전용 공유 프레임**을 활용한 프로세스 간 병합 매핑 | 중복 물리 프레임 제거 및 실가용 메모리 절약 |
| 순수 세그멘테이션 도입 시 **외부 단편화**로 인한 배치 한계 돌파 | **페이지 세그멘테이션 혼용** 모델 채택 | 외부 단편화 방지 및 논리적 보안 유지 장점 동시 수용 |
| 다중 프로세스 분기 및 생성 시 메모리 복사 오버헤드 지연 | **쓰기 시점 복사** 기법을 적용한 페이지 공간 생성 | 물리적 복사 지연 은닉 및 프로세스 생성 비용 극소화 |

#### 한줄 요약

- 작업 집합 제어, 공유 프레임 매핑, 혼용 모델 적용 및 쓰기 시점 복사 최적화를 통해 가상 메모리 비용을 통합 관리한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **메모리 가상화 선택 기준(Memory Virtualization Selection Criteria)**: 대상 시스템의 물리 용량, 코드 공유 요구, 성능 목표를 평가하여 페이징과 보호 기법을 결정하는 기준이다.

</details>

- 범용 아키텍처는 페이징을 표준으로 채택하며, 보안 구역 분리에는 혼용 모델을 유연하게 결합함

#### 한줄 요약

- 고정 페이지 단위의 주소 변환을 뼈대로 삼고 요구 적재와 공유 매핑 기술을 접목하여 메모리 한계를 지능적으로 방어해야 한다.
