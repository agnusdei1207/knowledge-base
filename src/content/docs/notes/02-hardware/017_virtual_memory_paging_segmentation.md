## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **가상 메모리(Virtual Memory)**: 프로세스에 물리 메모리와 분리된 논리 주소 공간을 제공해 비연속 배치와 프로세스 격리를 가능하게 하는 메모리 관리 기법.
- **페이징(Paging)**: 가상 주소 공간과 물리 메모리를 고정 크기 페이지·프레임 단위로 나누어 비연속 매핑하는 방식.
- **세그멘테이션(Segmentation)**: 코드·데이터·스택 같은 논리 단위를 가변 크기 세그먼트로 관리해 의미 단위 보호·공유를 지원하는 방식.

</details>

- 정의/개념: 가상 주소를 페이징·세그멘테이션으로 물리 주소에 매핑하는 **메모리 추상화 체계**
- 배경/필요성: 프로세스 격리·비연속 물리 배치·요구 적재로 소규모 물리 메모리에서 대규모 주소 공간 제공

#### 한줄 요약
- 프로그램은 연속된 큰 공간을 쓰는 것처럼 보지만, OS는 실제 메모리의 여러 위치에 나누어 필요한 부분만 올린다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **요구 페이징(Demand Paging)**: 실제 참조가 발생한 시점에만 해당 페이지를 물리 메모리에 적재하는 방식; 초기 적재 비용 감소.
- **비연속 할당(Non-Contiguous Allocation)**: 가상 주소상 연속된 페이지를 서로 다른 물리 프레임에 배치해 단편화 없이 메모리 사용.
- **메모리 보호(Memory Protection)**: 페이지·세그먼트별 읽기·쓰기·실행 권한으로 허가되지 않은 접근을 차단하는 기능.

</details>

- **요구 페이징**으로 참조 전 페이지를 적재하지 않아 초기 메모리 사용량 감소
- **비연속 할당**으로 물리 메모리의 분산 프레임을 연속 가상 공간으로 투명하게 제공
- 페이지·세그먼트별 **메모리 보호**로 프로세스 간 불법 접근 차단

#### 한줄 요약
- 필요한 부분만 물리 메모리에 올리고 서로 다른 프로세스의 주소를 분리해 작은 메모리로도 큰 공간과 안전한 격리를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블(Page Table)**: 가상 페이지 번호를 물리 프레임 번호와 접근 권한으로 변환하는 엔트리 집합.
- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 기준 주소·크기·접근 권한을 기록한 디스크립터 항목.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 접근 권한 검사를 하드웨어로 수행하는 장치.

</details>

```text
[가상 메모리 관리]
├─ MMU
│  ├─ 페이징 변환 (페이지 테이블)
│  └─ 세그멘테이션 변환 (세그먼트 기술자)
└─ 물리 프레임
```

선의 의미: 가지(`├─`)는 소유 관계; MMU는 페이징·세그멘테이션 변환을 거쳐 물리 프레임에 접근

| 구성요소 | 책임 |
|:---|:---|
| **MMU** | 가상→물리 주소 변환·접근 권한 검사 |
| 페이지 테이블 | 가상 페이지 번호·물리 프레임 번호·권한 매핑 |
| 세그먼트 기술자 | 논리 세그먼트의 기준 주소·크기·권한 관리 |
| 물리 프레임 | 변환된 실제 데이터·코드 저장 |

#### 한줄 요약
- MMU가 주소를 해석하고, 페이지 테이블과 세그먼트 기술자가 각각 고정 단위와 논리 단위의 배치 정보를 제공한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: 페이지가 비상주하거나 접근 권한 오류로 OS 예외 처리가 필요한 상황.
- **명령어 재시작(Instruction Restart)**: 예외 처리가 끝난 뒤 중단한 명령어를 처음부터 다시 실행하는 처리.

</details>

```text
CPU 가상 주소 접근
      │
      ▼
1. MMU 변환·권한 확인
      │
      ├─ 변환 성공·권한 OK → 물리 메모리 접근
      │
      └─ 비상주 또는 권한 오류 → 2. 페이지 폴트 예외
                                         │
                                   3. OS 핸들러: 페이지 적재
                                         │
                                   4. 명령어 재시작
```

**동작 원리**

1. **주소 변환**: MMU가 가상 페이지(또는 세그먼트+오프셋)를 물리 프레임 주소로 변환하고 권한 검사
2. **페이지 폴트**: 비상주·권한 오류 시 OS 폴트 핸들러 진입; 필요한 페이지를 저장장치에서 물리 프레임으로 적재
3. **명령어 재시작**: 페이지 적재 완료 후 폴트 발생 명령어를 처음부터 재실행

#### 한줄 요약
- 주소가 정상이면 바로 접근하고, 메모리에 없는 페이지면 OS가 자리를 마련한 뒤 같은 명령어를 다시 시작한다.

## Ⅴ. 종류 및 비교

| 메모리 관리 방식 | 페이징 | 세그멘테이션 | 페이지 세그멘테이션 |
|:---|:---|:---|:---|
| 적용 기준 | 고정 단위·비연속 배치 우선 | 논리 단위 보호·공유 우선 | 논리 구분과 고정 배치 동시 필요 |
| 핵심 특징 | 페이지·프레임 고정 크기 **비연속 매핑** | 가변 세그먼트·기준+한계 레지스터 | 세그먼트 내부 **페이지 테이블** 추가 |
| 한계 | **내부 단편화**·페이지 테이블 메모리 비용 | **외부 단편화**·가변 배치 관리 복잡도 | 변환 단계 증가·관리 복잡도 |

#### 한줄 요약
- 페이징은 관리와 배치가 단순하고, 세그멘테이션은 논리 단위 보호가 쉽지만, 둘을 결합하면 두 단계 변환 비용이 생긴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 시점 복사(Copy-on-Write, CoW)**: 공유 페이지에 쓰기가 발생할 때만 별도 물리 페이지를 복사하는 방식.
- **쓰레싱(Thrashing)**: 페이지 교체 입출력이 실제 실행 시간보다 많아져 시스템이 심하게 느려지는 상태.
- **내부 단편화(Internal Fragmentation)**: 고정 크기 페이지의 남은 공간이 낭비되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리 부족으로 **쓰레싱** 발생 | 작업 집합 기준 프레임 배분·동시 실행량 조절 | 페이지 입출력 폭증 완화 |
| 큰 페이지가 **내부 단편화** 유발 | 연속 접근 영역에만 대형 페이지 선택 적용 | 커버리지·공간 효율 균형 |
| 프로세스 생성 시 전체 메모리 복사 비용 | **CoW** 기반 페이지 공유 | 초기 생성 시간·메모리 사용 감소 |
| 세그멘테이션 가변 배치의 **외부 단편화** | 페이징 결합·물리 프레임 연속성 보장 | 배치 실패·관리 부담 완화 |

#### 한줄 요약
- 가상 메모리는 주소 변환만의 문제가 아니라, 페이지 크기·프레임 배분·복사 시점까지 함께 조절해야 성능이 유지된다.

## Ⅶ. 결론

- 범용 OS는 **작업 집합**과 보호 요구를 기준으로 **페이징**을 우선하고, 논리 단위 보호가 핵심이면 세그멘테이션 또는 결합 방식을 선택

#### 한줄 요약
- 현대 시스템에서는 고정 페이지의 관리 이점을 기본으로 삼되, 프로그램 보호 단위와 메모리 압박에 맞춰 페이지 크기와 적재 정책을 조정한다.
