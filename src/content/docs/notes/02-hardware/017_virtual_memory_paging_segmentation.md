## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **가상 메모리(Virtual Memory)**: 프로세스별 독립 주소 공간을 물리 프레임에 매핑해 격리와 요구 적재를 제공하는 방식.
- **물리 프레임(Physical Frame)**: 물리 메모리를 페이지와 같은 고정 크기로 나눈 저장 단위.
- **페이징(Paging)**: 가상 주소를 고정 크기 페이지와 물리 프레임으로 변환하는 방식.
- **세그멘테이션(Segmentation)**: 가상 주소를 가변 논리 영역의 기준 주소와 한계로 변환하는 방식.
- **접근 격리(Access Isolation)**: 한 프로세스가 권한 없는 다른 프로세스의 물리 메모리를 읽거나 쓰지 못하도록 차단하는 성질.

</details>

- 정의/개념: 프로세스별 논리 주소를 물리 메모리에 매핑하는 **가상 메모리** 방식
- 배경/필요성: 물리 메모리 주소를 프로세스가 직접 참조하면 주소 공간 격리 불가능

#### 한줄 요약

- 가상 메모리는 프로세스별 주소 공간을 물리 메모리에 독립적으로 매핑하고 접근 권한을 검사해 프로세스 간 메모리를 격리한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **가상 주소 공간(Virtual Address Space)**: 각 프로세스가 독립적으로 사용하는 논리 주소 범위.
- **요구 페이징(Demand Paging)**: 모든 페이지를 미리 올리지 않고 참조 시점에 물리 메모리에 적재하는 방식.
- **비상주 페이지(Non-Resident Page)**: 주소 공간에는 존재하지만 현재 물리 프레임에 올라와 있지 않은 페이지.
- **보조기억장치(Secondary Storage)**: 비상주 페이지를 보관하고 페이지 폴트 때 주기억장치로 읽어 오는 SSD•디스크 등의 저장장치.

</details>

- 프로세스별 독립 **가상 주소 공간**으로 상호 접근 차단
- 가상·물리 주소 분리로 **비상주 페이지**까지 주소화
- 참조 시점에만 프레임을 잡는 **요구 페이징**

#### 한줄 요약

- 프로세스별 가상 주소 공간은 상호 접근을 차단하고, 보조기억장치까지 포함한 주소 공간을 제공하며, 요구 페이징으로 참조하는 페이지만 물리 메모리에 적재한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 접근 권한을 검사하는 하드웨어.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 주소 변환을 저장하는 캐시.
- **페이지 테이블 항목(Page Table Entry, PTE)**: PPN•상주 여부•접근 권한을 저장하는 항목.
- **세그먼트 기술자(Segment Descriptor)**: 논리 영역의 기준 주소•한계•접근 권한을 저장하는 항목.
- **물리 페이지 번호(Physical Page Number, PPN)**: 매핑된 물리 페이지 프레임의 번호.
- **페이지 테이블(Page Table)**: 가상 페이지별 물리 프레임 번호와 상주 상태•접근 권한을 기록하는 자료 구조.
- **권한 검사(Permission Check)**: 변환된 주소의 읽기·쓰기·실행 접근이 허용됐는지 확인하는 보호 절차.

</details>

```text
가상 메모리 변환 구조
├─ MMU•TLB
├─ 페이징 메타데이터
│  └─ 페이지 테이블
├─ 세그멘테이션 메타데이터
│  └─ 세그먼트 기술자
└─ 물리 메모리
```

가지의 의미: 변환 방식별 메타데이터와 물리 저장소의 정적 구성.

| 구성요소 | 책임 |
|:---|:---|
| MMU•TLB | 주소 변환 캐시와 **권한 검사** |
| 페이지 테이블 | PPN•상주•권한 제공 |
| 세그먼트 기술자 | 기준•한계•권한 제공 |
| 물리 메모리 | 물리 프레임 데이터 제공 |

#### 한줄 요약
- MMU가 페이지 테이블이나 세그먼트 기술자를 조회해 가상 주소를 물리 메모리 위치로 변환한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **페이지 폴트(Page Fault)**: 비상주 페이지 접근을 운영체제에 알려 적재와 매핑 갱신을 요청하는 예외.
- **명령 재시작(Instruction Restart)**: 페이지 적재와 매핑 갱신 후 중단된 메모리 접근을 다시 실행하는 동작.
- **가상 페이지 번호(Virtual Page Number, VPN)**: 가상 주소의 페이지 번호.
- **TLB 적중(TLB Hit)**: 주소 변환을 TLB에서 즉시 찾은 상태.
- **TLB 미스(TLB Miss)**: 주소 변환을 찾지 못해 페이지 테이블을 조회해야 하는 상태.
- **접근 예외(Access Exception)**: 주소 범위나 접근 권한 검사가 실패했음을 운영체제에 알리는 예외.

</details>

```text
1. 가상 주소·접근 유형 입력
        │
        ▼
2. 주소 변환 메타데이터 조회
├─ 페이징
│  └─ TLB 조회
│     ├─ 적중•허용: PPN+오프셋
│     └─ 미스: 페이지 테이블 조회
│        ├─ 상주: TLB 채움
│        └─ 비상주: 페이지 폴트
└─ 세그멘테이션
   └─ 세그먼트 기술자 조회
      ├─ 한계 내: 기준 주소 확인
      └─ 한계 초과: 접근 예외
        │
        ▼
3. 접근 권한 검사
   ├─ 위반: 접근 예외
   └─ 허용
      ▼
4. 물리 주소 생성·메모리 접근
```

### 동작 원리

1. **가상 주소 입력**: 프로세서가 가상 주소와 접근 유형을 MMU에 전달.
2. **변환 메타데이터 조회**: 페이징은 **VPN**으로 TLB·페이지 테이블 조회, 세그멘테이션은 기술자 조회.
3. **상주·범위·권한 판정**: 비상주 페이지는 **페이지 폴트**로 적재 후 **명령 재시작**, 범위 초과나 권한 위반은 **접근 예외**.
4. **물리 주소 생성**: PPN 또는 기준 주소에 오프셋을 결합해 물리 메모리 접근.

#### 한줄 요약

- MMU는 페이징의 페이지 테이블 또는 세그멘테이션의 기준 주소·한계를 조회하고 권한을 검사한 뒤 물리 주소를 생성한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **내부 단편화(Internal Fragmentation)**: 고정 크기 블록 내부에 남는 자투리 공간.
- **외부 단편화(External Fragmentation)**: 가변 크기 영역 사이에 흩어져 남는 빈 공간.
- **오프셋(Offset)**: 페이지나 세그먼트 안의 위치. 기준 번호나 주소만 변환한 뒤 그대로 더하는 주소 하위 부분.
- **기준 주소(Base Address)**: 세그먼트가 시작하는 물리 메모리 위치.
- **한계(Limit)**: 세그먼트 안에서 접근을 허용하는 최대 오프셋 범위.
- **비연속 프레임 배치(Non-Contiguous Frame Allocation)**: 한 프로세스의 페이지를 서로 떨어진 물리 프레임에 나누어 놓는 방식.

</details>

| 주소 변환 방식 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 적용 기준 | **요구 페이징**과 비연속 물리 프레임 배치 필요 시 | 코드·스택 등 논리 영역별 경계와 권한 필요 시 |
| 핵심 특징 | 고정 크기 페이지의 **비연속 프레임 배치** | 가변 논리 영역의 **기준 주소•한계** 변환 |
| 한계 | 페이지 자투리의 **내부 단편화** | 연속 자리를 못 잡는 **외부 단편화** |

> 요약: 두 방식 모두 상위 주소 정보를 변환하고 영역 내부 **오프셋**은 유지.

#### 한줄 요약

- 페이징은 VPN을 프레임 번호로 바꿔 비연속 배치하고, 세그멘테이션은 기준 주소에 오프셋을 더해 연속 영역에 배치한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **쓰레싱(Thrashing)**: 작업 집합보다 프레임이 부족해 계산보다 페이지 입출력에 더 많은 시간을 쓰는 상태.
- **주 페이지 폴트(Major Page Fault)**: 저장장치 I/O가 필요한 페이지 폴트.
- **부 페이지 폴트(Minor Page Fault)**: 메모리 안의 프레임을 다시 매핑하는 페이지 폴트.
- **읽기 전용 공유 프레임(Read-Only Shared Frame)**: 여러 프로세스가 같은 라이브러리 코드를 안전하게 함께 쓰도록 쓰기를 금지한 물리 페이지.
- **사전 적재(Prefetching)**: 요청 전에 예상 페이지를 메모리에 올리는 방법.
- **워밍업(Warm-Up)**: 자주 쓰는 경로를 미리 실행해 초기 폴트를 줄이는 방법.
- **최소 권한(Least Privilege)**: 필요한 읽기•쓰기•실행 권한만 부여하는 원칙.
- **TLB 무효화(TLB Invalidation)**: 변경된 매핑의 오래된 TLB 변환을 제거하는 절차.
- **공유 라이브러리(Shared Library)**: 여러 프로세스가 공통으로 사용하는 코드. 읽기 전용 물리 프레임을 함께 매핑 가능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 집합보다 프레임 부족으로 **쓰레싱** 발생 | **주·부 페이지 폴트율** 측정해 메모리 한도와 동시 실행량 조정 | 저장장치 페이지 I/O 감소 |
| 시작 구간에서 필요한 페이지 없어 폴트 폭증 | 접근 패턴에 맞춘 **사전 적재·워밍업** 적용 | 초기 페이지 폴트와 응답 지연 완화 |
| 매핑 변경 후 오래된 TLB 엔트리로 격리 훼손 | **최소 권한**·**TLB 무효화** 절차 검증 | 최신 매핑과 권한에 따른 메모리 보호 유지 |
| 고정·가변 영역 배치로 **내부·외부 단편화** | 페이지 크기와 세그먼트 배치·사용률 관찰 | 낭비 공간 감소로 메모리 활용률 개선 |
| 프로세스마다 같은 **공유 라이브러리** 중복 적재 | 코드 페이지를 **읽기 전용 공유 프레임**에 매핑 | 중복 프레임 제거로 물리 메모리 사용량 절감 |

#### 한줄 요약

- 공유 라이브러리 코드는 읽기 전용 물리 프레임을 여러 주소 공간에 함께 매핑해 격리를 유지하면서 중복 적재를 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **요구 적재(Demand Loading)**: 접근한 데이터만 물리 메모리에 올려 공간을 절약하는 운용 방식.
- **논리 권한 경계(Logical Permission Boundary)**: 코드•데이터•스택 같은 영역마다 서로 다른 범위와 접근 권한을 적용하는 구분.

</details>

- **요구 적재**는 **페이징**, **논리 권한 경계**는 **세그멘테이션** 선택

#### 한줄 요약

- 빈자리를 활용하며 필요한 만큼만 올리면 페이징을 선택하고, 영역별 권한과 경계 검사가 목적이면 세그멘테이션을 선택한다.
