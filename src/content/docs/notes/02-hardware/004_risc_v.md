## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RISC-V**: 오픈 표준 라이선스 기반으로 기본 정수 명령어 세트(Base ISA)와 모듈형 표준/커스텀 확장을 제공하는 로열티 프리 개방형 명령어 집합 구조.
- **개방형 ISA(Open Standard ISA)**: 특정 기업의 독점 라이선스 없이 누구나 자유롭게 하드웨어를 구현하고 특화 기능을 추가할 수 있도록 공개된 표준 규격.
- **명세 기반 호환성(Specification-Based Compatibility)**: 마이크로아키텍처의 세부 물리 구현과 무관하게 공식 ISA 명세를 준수하여 동일 바이너리의 상호 운용성을 보장하는 성질.

</details>

- 정의/개념: 공개된 최소 정수 규격과 모듈형 확장을 조합하여 반도체 칩마다 최적화된 명령어를 자유롭게 구성할 수 있는 **개방형 명령어 집합 구조(RISC-V)**
- 배경/필요성: 기존 상용 독점 ISA의 **라이선스 비용 부담, 독점 벤더 종속 및 도메인 특화 가속 명령어(Custom Extension) 추가 제약** 극복

#### 한줄 요약
- RISC-V의 본질은 로열티 절감을 넘어 설계자가 원하는 도메인 특화 명령어를 하드웨어에 직접 추가할 수 있는 아키텍처 자율성이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 ISA(Base ISA)**: 정수 연산 및 기본 분기 제어를 정의하여 모든 RISC-V 하드웨어가 반드시 준수해야 하는 고정 불변의 최소 필수 세트(RV32I/RV64I).
- **표준 확장(Standard Extension)**: 공식 표준화 위원회의 승인을 받아 Opcode가 배정된 모듈형 확장 세트(M: 곱셈/나눗셈, A: 원자적 연산, F/D: 부동소수점, C: 압축, V: 벡터).
- **사용자 정의 확장(Custom Extension)**: 표준 인코딩과 충돌하지 않도록 사전에 비워둔 커스텀 예약 공간(Custom Opcode)을 활용하여 독자 가속 회로를 구현하는 확장.

</details>

- 최소주의와 모듈성: **기본 ISA(RV32I/RV64I)**에 필요한 **표준 확장**만 선택 결합하여 불필요한 실리콘 면적과 누설 전력 원천 차단
- 충돌 없는 커스텀 확장: 사전에 예약된 독립 Opcode 공간을 통해 독자적인 **사용자 정의 확장**을 추가해도 표준 생태계와 공존 가능
- 에코시스템 호환성: 하드웨어 구현이 달라져도 **명세 기반 호환성**을 충족하여 공통 컴파일러(GCC/LLVM), OS(Linux), 툴체인을 그대로 공유

#### 한줄 요약
- 기본 정수 세트는 절대 변하지 않고 필요한 확장만 레고 블록처럼 끼워 맞추는 모듈형 설계로 파편화를 억제하면서 특화 가속을 구현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **권한 아키텍처(Privileged Architecture)**: User(U-mode: 사용자 앱), Supervisor(S-mode: OS 커널), Machine(M-mode: 하드웨어 제어/펌웨어)의 3단계 실행 특권 계층을 규정한 시스템 명세.
- **제어 및 상태 레지스터(Control and Status Register, CSR)**: 프로세서 동작 모드 전환, 인터럽트 인에이블, 가상 메모리 페이징 활성화(satp), 성능 카운터를 제어하는 시스템 특수 레지스터.
- **ISA 프로파일(ISA Profile)**: 특정 OS(Linux 등) 실행에 필요한 필수 표준 확장의 조합을 표준화하여 소프트웨어 배포 바이너리 호환성을 보장하는 공식 규격.

</details>

```text
[RISC-V 표준 명세 체계]
 ├─ [기본 정수 ISA] ─── RV32I / RV64I (32개 범용 레지스터 및 기본 정수 연산)
 │
 ├─ [모듈형 확장 세트]
 │   ├─ 표준 확장: M (곱/나눗셈), A (원자 연산), F/D (부동소수점), C (압축), V (벡터), B (비트 조작)
 │   └─ 사용자 정의 확장: Custom-0 ~ Custom-3 전용 예약 Opcode 공간
 │
 ├─ [권한 아키텍처 (Privileged Levels)]
 │   ├─ M-Mode (Machine: 최고 권한 펌웨어)
 │   ├─ S-Mode (Supervisor: OS 커널 및 가상 메모리)
 │   └─ U-Mode (User: 사용자 애플리케이션)
 │
 └─ [ISA 프로파일 규격] ─── RVA (애플리케이션용), RVM (마이크로컨트롤러용)
```

선의 의미: 가지(`├─`, `└─`)는 명세 계층의 소유 및 구성 관계; ISA 프로파일은 상위 소프트웨어 생태계 호환성을 위해 확장 조합을 표준으로 묶어줌

| 구성요소 | 계층 및 영역 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **기본 ISA** | 필수 코어 규격 | 정수 연산, 메모리 Load/Store, 기본 분기 규정 | 고정 불변, 최소 40여 개 명령어 |
| **표준 확장** | 선택 모듈 규격 | 부동소수점, 벡터, 원자적 연산 등 표준 기능 확장 | 합의된 공식 Opcode 및 툴체인 완벽 지원 |
| **사용자 정의 확장** | 도메인 특화 영역 | AI·암호·신호처리용 커스텀 가속 회로 결합 | 예약된 Custom Opcode 영역 사용 |
| **권한 아키텍처** | 시스템/보안 계층 | U/S/M 모드 권한 분리 및 **CSR** 레지스터 통제 | OS 커널 및 하이퍼바이저 격리 지원 |
| **ISA 프로파일** | 플랫폼 호환 규격 | 상용 OS(Linux/Android) 구동에 필요한 확장 세트 강제 | 소프트웨어 생태계 파편화 방지 |

#### 한줄 요약
- RISC-V는 기본 정수 세트 위에 표준/커스텀 확장을 올리고, 3단계 권한 모델과 ISA 프로파일을 통해 시스템 안정성과 소프트웨어 호환성을 확보한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **적합성 시험(Compliance Test)**: 하드웨어 코어가 공식 RISC-V 명세의 명령어 동작, CSR 상태 변화, 예외 처리를 정확히 준수하는지 검증하는 공식 테스트.
- **차등 시험(Differential Testing)**: 공식 소프트웨어 골든 시뮬레이터(Spike)와 실제 RTL 하드웨어 시뮬레이션에 동일 입력을 주입해 출력 레지스터 상태를 사이클 단위로 대조하는 검증 기법.

</details>

```text
1. 워크로드 요구사항 분석 (초저전력 임베디드 vs 고성능 Linux 서버)
                      │
                      ▼
2. ISA 모듈 조합 및 확장 결정
   ┌──────────────────┴──────────────────┐
[ 표준 프로파일 채택 ]                 [ 사용자 정의 확장 결합 ]
   │ (예: RVA22 = RV64GCBK)               │ (AI/암호 가속기 결합)
   │                                      ▼
   │                               예약된 Custom Opcode 인코딩 검증
   └──────────────────┬──────────────────┘
                      │
                      ▼
3. RTL 하드웨어 설계 및 프로세서 파이프라인 구현
                      │
                      ▼
4. 적합성 시험 및 차등 시험(Differential Testing) 수행
   ┌──────────────────┴──────────────────┐
 [ 불일치 발생 ]                       [ 전수 통과 ]
   │                                      │
   ▼                                      ▼
RTL 결함 수정 후 재검증           표준 프로파일 선언 및 OS/도구 배포
```

분기 결과: **표준 확장은** 기존 상용 툴체인을 즉시 사용 가능하나, **사용자 정의 확장은** 컴파일러 백엔드 확장과 커스텀 시뮬레이터 개발이 수반됨

#### 한줄 요약
- RISC-V 프로세서 개발은 모듈 선택 ➔ 커스텀 확장 설계 ➔ RTL 구현 ➔ 차등 시험 검증 ➔ 툴체인 연동의 표준화된 파이프라인을 거친다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 표준 확장 (Standard Extension) | 사용자 정의 확장 (Custom Extension) |
|:---|:---|:---|
| 적용 기준 | 공통 컴파일러 및 범용 OS 생태계 활용 필수 시 | 독자적인 도메인 특화 하드웨어 가속(AI/DSP/보안) 시 |
| 핵심 특징 | **국제 위원회 승인 공식 Opcode 배정, 바이너리 호환** | **예약된 Custom 공간 활용, 독자 실행 유닛 직접 제어** |
| 한계 | 신규 표준 제정까지 긴 합의 기간 소요 | 독자 컴파일러 유지보수 부담 및 타 구현체와의 비호환 |
| 생태계 지원 | GCC, LLVM, Linux, Android 기본 탑재 | 커스텀 인라인 어셈블리 또는 툴체인 패치 필수 |

#### 한줄 요약
- 범용 소프트웨어 호환성이 우선이면 표준 확장을 조합하고, 극한의 전력 대 성능비 가속이 필요하면 사용자 정의 확장을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **기능 탐지(Feature Discovery)**: 소프트웨어가 런타임에 CSR(misa 등) 또는 디바이스 트리(Device Tree)를 조회하여 현재 하드웨어가 지원하는 ISA 확장을 동적으로 판별하는 기법.
- **ABI(Application Binary Interface)**: 레지스터 호출 규약(Calling Convention) 및 데이터 정렬 방식을 규정한 기계어 인터페이스.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 반도체 제조사별 확장 조합 상이로 인한 소프트웨어 파편화 | 표준 **ISA 프로파일(RVA22/23)** 준수 및 **기능 탐지** 적용 | 공통 배포 바이너리의 상호 운용성 확보 |
| 커스텀 명령어가 향후 제정될 신규 표준 Opcode와 충돌 | 공식 규격의 **Custom-0~3 예약 인코딩 영역**에만 배치 | 표준 발전 시에도 하드웨어 재설계 방지 |
| 마이크로아키텍처의 예외 및 CSR 동작이 명세와 미세 불일치 | **적합성 시험(ACT)** 및 **차등 시험(Differential Testing)** 자동화 | OS 부팅 단계의 치명적 시스템 크래시 사전 차단 |

#### 한줄 요약
- RISC-V 실무 도입 시에는 프로파일 기반의 파편화 통제와 예약 인코딩 준수, 그리고 철저한 차등 시험 검증 체계 구축이 필수적이다.

## Ⅶ. 결론

- 반도체 주권 확보 및 도메인 특화 가속을 위해 **RISC-V 개방형 ISA를 기반으로 표준 확장과 사용자 정의 확장을 모듈화 적용**하고, 소프트웨어 생태계 파편화를 방지하기 위해 **공식 ISA 프로파일과 자동화된 적합성·차등 시험 체계**를 확립하여 고효율 특화 프로세서 상용화 달성

#### 한줄 요약
- RISC-V는 개방성과 모듈성을 통해 특화 가속 반도체 시장을 주도하고 있으며, 프로파일 준수와 검증 자동화가 성공적인 도입의 핵심이다.
