## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RISC-V**: 공개 명세를 기반으로 기본 ISA와 확장을 자유롭게 조합할 수 있는 개방형 명령어 집합 구조.
- **개방형 ISA(Open ISA)**: 명세를 공개해 라이선스 제약 없이 여러 주체가 호환 구현을 개발할 수 있는 ISA 방식.
- **명세 기반 호환성(Specification-Based Compatibility)**: 구현 방식이 달라도 같은 명세의 프로그램 관찰 결과를 동일하게 보장하는 성질.

</details>

- 정의/개념: 로열티 없는 **공개 명세**와 **모듈형 확장 구조**를 지원하는 차세대 프로세서 명령어 집합 규격
- 배경/필요성: 기존 독점 ISA의 **라이선스 비용 부담** 및 전용 코어 설계 변경 제약 심화

#### 한줄 요약
- RISC-V는 누구나 같은 명세를 보고 코어를 만들고 필요한 기능만 확장으로 더할 수 있는, 특허 비용 없는 오픈 표준 ISA다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 ISA(Base ISA)**: 정수 레지스터와 기본 명령어 동작을 정의하는 최소 공통 규격(RV32I·RV64I 등).
- **표준 확장(Standard Extension)**: 곱셈(M)·원자 연산(A)·부동소수점(F/D)·벡터(V)처럼 명세 위원회가 합의한 추가 기능.
- **사용자 정의 확장(Custom Extension)**: 표준 인코딩 공간과 구분된 비트 패턴에 제품 특화 연산을 추가하는 확장.

</details>

- 기본 ISA와 확장의 모듈형 조합으로 **전력 및 면적 최적화**
- **사용자 정의 확장**으로 AI·암호화 같은 도메인 특화 연산을 이식성 손상 없이 추가
- 구현 방식과 무관하게 **명세 기반 호환성**을 유지해 바이너리·도구 생태계 공유

#### 한줄 요약
- 표준 기본은 맞추고 특화 기능은 확장으로 분리해, 여러 제품이 같은 컴파일러·OS·라이브러리를 쓸 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **권한 아키텍처(Privileged Architecture)**: 예외·인터럽트·보호 모드의 시스템 동작을 정의하는 규격.
- **제어 및 상태 레지스터(Control and Status Register, CSR)**: 권한 상태·예외 원인·제어 값을 보관하는 레지스터.
- **ISA 프로파일(ISA Profile)**: 특정 운영체제나 생태계에 필요한 확장 조합을 고정한 호환 기준.

</details>

```text
[RISC-V 명세]
├─ 기본 ISA (RV32I / RV64I / RV128I)
│  └─ 정수 레지스터·기본 명령어
├─ 표준 확장 (M·A·F·D·V 등)
├─ 사용자 정의 확장
├─ 권한 아키텍처
│  └─ CSR
└─ ISA 프로파일
```

선의 의미: 가지(`├─`)는 명세 계층 소유 관계, `└─`는 하위 구성요소

| 구성요소 | 책임 |
|:---|:---|
| 기본 ISA | 공통 명령어·**레지스터** 동작 규정으로 최소 호환 기준 제공 |
| 표준 확장 | 범용 기능의 호환 명령어로 도구·바이너리 공유 기반 |
| 사용자 정의 확장 | 도메인 특화 연산 추가로 표준 인코딩과 충돌 없이 특화 |
| 권한 아키텍처 | 예외·인터럽트·**CSR** 동작으로 OS 이식성 보장 |
| ISA 프로파일 | 목표 소프트웨어의 확장 범위 고정으로 배포 호환성 확정 |

#### 한줄 요약
- 기본 ISA가 공통 뼈대라면, 표준 확장은 검증된 살이고, 사용자 정의 확장은 제품마다 다른 근육이며, 프로파일이 그 조합의 경계를 정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **레지스터 전송 수준(Register-Transfer Level, RTL)**: 레지스터 간 데이터 이동과 논리 연산으로 회로를 기술하는 설계 추상 수준.
- **적합성 시험(Compliance Test)**: 구현이 ISA 명세의 명령어와 예외 동작을 정확히 지키는지 확인하는 시험.
- **차등 시험(Differential Testing)**: 참조 구현과 대상 구현에 동일 입력을 주어 실행 결과를 비교하는 검증 기법.

</details>

```text
요구 분석: OS·성능·전력 조건 확정
        │
        ▼
1. ISA 조합 선택: 기본 ISA + 필요한 표준/사용자 정의 확장
        │
        ▼
2. RTL 구현: 명령어·권한 상태·예외 동작 회로 반영
        │
        ▼
3. 적합성 및 차등 시험: 명세와 참조 구현 결과 일치 확인
        │
        ├─ 불일치 → RTL 수정 후 재시험
        │
        └─ 일치 → 배포 및 소프트웨어 생태계 연동
```

**동작 원리**

1. **ISA 조합 선택**: 기본 ISA에 표준 및 사용자 정의 확장 선택
2. **RTL 구현**: 선택한 명령어와 권한 아키텍처, CSR 회로 구현
3. **적합성 및 차등 시험**: 적합성 시험으로 명세 준수 확인 후 배포

#### 한줄 요약
- RISC-V 코어는 먼저 지원할 확장을 정하고, 그 약속대로 회로를 만든 뒤 명세와 비교·검증해야 생태계에 합류할 수 있다.

## Ⅴ. 종류 및 비교

| 확장 유형 | 표준 확장 | 사용자 정의 확장 |
|:---|:---|:---|
| 적용 기준 | 여러 구현·제품에서 공통 기능 호환 필요 | 특정 제품에서만 필요한 특화 연산 추가 |
| 핵심 특징 | 명세·도구·**바이너리 호환성** 공유 | 도메인 특화 연산과 데이터 경로 독립 추가 |
| 한계 | 기능 추가·변경이 명세 위원회 합의 필요 | 이식성·도구 지원·**적합성 시험** 부담 증가 |

#### 한줄 요약
- 여러 제품에서 함께 쓸 기능은 표준 확장에 두고, 한 제품에서만 쓸 기능은 사용자 정의 확장에 분리해 생태계 오염을 막는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **응용 프로그램 이진 인터페이스(Application Binary Interface, ABI)**: 컴파일된 코드가 OS·라이브러리와 상호작용하는 호출 규약·데이터 배치 기준.
- **예약 인코딩(Reserved Encoding)**: 미래 표준화나 지정 용도를 위해 임의 사용을 금지한 명령어 비트 패턴.
- **기능 탐지(Feature Discovery)**: 실행 환경에서 지원하는 확장을 조회해 코드 실행 경로를 결정하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 구현별 확장 차이로 바이너리 실행 실패 | **ISA 프로파일**·ABI 고정과 기능 탐지 적용 | 배포 대상과 실행 조건 명확화 |
| 사용자 정의 명령이 표준 인코딩과 충돌 | 사용자 정의 인코딩 공간 사용·**예약 인코딩** 회피 | 향후 표준 확장과의 충돌 방지 |
| 권한 아키텍처 구현이 명세와 불일치 | 적합성 시험·**차등 시험** 자동화 적용 | 규격 오류 조기 발견·OS 이식성 확보 |
| 확장용 컴파일러 지원 범위 불명확 | 도구 버전 고정과 빌드 회귀 시험 적용 | 개발 환경 재현성·이식성 확보 |

#### 한줄 요약
- 확장 기능 자체보다 ABI·인코딩 충돌·도구 지원 범위를 먼저 관리해야 다른 구현과 공존할 수 있다.

## Ⅶ. 결론

- 특화 연산과 구현 자율성은 **RISC-V**, 생태계 호환성은 **ISA 프로파일** 기준 확정

#### 한줄 요약
- RISC-V는 명세가 열려 있다는 이점만으로 고르는 것이 아니라, 필요한 확장과 이를 뒷받침할 도구·검증 체계를 갖출 때 선택한다.
