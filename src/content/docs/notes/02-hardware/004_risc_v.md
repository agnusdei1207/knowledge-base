## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RISC-V**: 기본 정수 명령어와 표준/사용자 정의 확장을 조합하는 로열티 없는 개방형 표준 ISA이다.
- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 프로세서를 제어하기 위한 명령어 체계와 메모리 접근 방식을 정의하는 인터페이스이다.
- **개방형 ISA 규격(Open ISA Specification)**: 특정 기업의 라이선스 종속 없이 하드웨어 코어를 구현하거나 명령어를 확장하도록 사양이 공개된 규격이다.
- **사용자 정의 확장(Custom Extension)**: 도메인 특화 연산을 위해 예약된 커스텀 인코딩 영역에 독자 명령어를 추가하는 하드웨어 확장 체계이다.

</details>

- 정의: 모듈형 설계를 바탕으로 기본 정수 명령어에 각종 확장을 자유롭게 결합하는 **개방형 ISA 규격**
- 배경: 기존 독점 구조의 라이선스 비용과 확장 제약을 해소하고 특화 코어의 독자적인 개발을 지원하기 위함

#### 한줄 요약

- RISC-V는 무료 개방형 라이선스를 바탕으로 기본 명령어와 모듈 확장을 조합하여 특화 프로세서를 자유롭게 구현할 수 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 ISA(Base ISA)**: RISC-V 호환 코어가 의무적으로 구현해야 하는 최소 단위의 정수 연산 명령어 집합이다.
- **표준 확장(Standard Extension)**: RISC-V 표준 위원회가 관리하는 공식 사양으로 곱셈, 원자적 연산, 부동소수점, 벡터 등의 모듈형 확장 세트이다.
- **마이크로아키텍처(Microarchitecture)**: 동일한 ISA 사양을 만족시키면서 제조업체가 독자적으로 설계한 물리적 프로세서 회로이다.

</details>

- 라이선스 및 로열티 비용이 없는 **개방형 ISA 규격**을 채택하여 독자적인 반도체 칩 코어 설계 및 특화 제작을 허용함.
- **기본 ISA**에 **표준 확장**과 연산용 **사용자 정의 확장**을 모듈식 블록 형태로 자유롭게 조합함.
- 명령어 사양과 칩 내부의 **마이크로아키텍처**를 분리하여 동일 규격 기반의 다양한 구현체를 생성함.

#### 한줄 요약

- 기본 명령어 기반의 모듈식 확장 조합을 통해 다양한 파이프라인 마이크로아키텍처 구현이 가능하다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ISA 프로파일(ISA Profile)**: 범용 운영체제 구동 및 생태계 호환성을 위해 필수 확장 조합을 묶은 표준 프로파일이다.
- **권한 아키텍처(Privileged Architecture)**: 모드 간 격리와 시스템 예외 및 인터럽트 처리를 규정한 하드웨어 사양이다.
- **XLEN**: 프로세서 정수 레지스터의 기본 비트 폭으로 32비트, 64비트, 128비트를 의미한다.
- **공통 실행 계약(Common Execution Contract)**: 코어 종류에 무관하게 동일한 결과를 얻도록 보장하는 기본 동작 규약이다.
- **특권 동작(Privileged Operation)**: 하이퍼바이저 및 커널 보안을 위해 특정 권한 모드에서만 접근이 허용되는 레지스터 조작이다.
- **제어 및 상태 레지스터(Control and Status Register, CSR)**: 프로세서의 동작 모드와 예외 처리를 제어하는 특수 레지스터이다.

</details>

```text
[ 아키텍처 계층 구조 ]
┌───────────────────────────────────────────────────────────┐
│  ISA Profile (e.g., RVA22: RV64GC + Vector Extensions)    │
├───────────────────────────────┬───────────────────────────┤
│  Base ISA (RV32I / RV64I)     │  Extensions (M, A, F, D)  │
├───────────────────────────────┴───────────────────────────┤
│  Privileged Architecture (M-Mode / S-Mode / U-Mode CSRs)  │
└───────────────────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| 기본 ISA | **XLEN** 정수 연산의 공통 실행 계약을 규정 |
| 확장 집합 | 산술, 벡터 및 **사용자 정의 확장** 명령 선택 |
| 권한 아키텍처 | 동작 모드 제어, **제어 및 상태 레지스터**와 예외 규정 |
| ISA 프로파일 | 필수 확장 조합을 통해 호환 대상 고정 |

#### 한줄 요약

- 기본 명령어와 모듈형 확장, 권한 아키텍처 규격을 조합하여 표준 프로파일을 고정하고 호환성을 확보한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **레지스터 전송 수준(Register Transfer Level, RTL)**: 동기식 플립플롭과 조합 논리 회로 동작을 정의하는 하드웨어 논리 설계 모델이다.
- **적합성 시험(Compliance Test)**: 구현된 코어가 공식 명령어 및 특권 사양을 완벽히 충족하는지 점검하는 테스트이다.
- **인코딩 계약(Encoding Contract)**: 기본 연산자와 커스텀 명령어 할당 영역의 상호 중복 방지 규약이다.
- **예외 시험(Exception Test)**: 메모리 보호 위반 등 발생 시 레지스터가 표준 규격대로 예외 처리를 하는지 검증하는 시험이다.
- **권한 시험(Privilege Test)**: 시스템 레지스터 접근 시 정해진 하드웨어 보안 예외를 발생시키는지 검증하는 절차이다.

</details>

```text
1. [ 목표 프로파일·확장 선택 ]
             │
             ▼
       2. [ 코어 RTL 구현 ]
             │
             ▼
3. [ 적합성 검증 코드 생성 ]
             │
             ▼
       4. [ 적합성 시험 ] ──> 불일치: 재검증, 통과: 툴체인 적용
```

### 동작 원리

1. 목표 선택: 시스템 성능 목적에 맞추어 필수 확장 및 커스텀 비트 영역을 정의함.
2. RTL 구현: 선택된 사양서에 의거하여 **레지스터 전송 수준** 회로를 설계함.
3. 검증 코드 생성: 표준 **인코딩 계약**에 기반한 기계어와 **예외 시험** 코드를 생성함.
4. 적합성 시험: 에뮬레이션 결과를 기대값과 비교하는 **적합성 시험**을 통해 규격 미준수 오류를 사전에 제거함.

#### 한줄 요약

- 목표 프로파일을 선정하고 하드웨어 설계를 완료한 뒤 적합성 시험 기반 검증을 수행하여 코어 개발을 완결한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Arm**: 독점적 명령어 집합을 바탕으로 검증된 상용 IP 라이선싱을 제공하는 아키텍처 벤더이다.
- **확장 파편화(Extension Fragmentation)**: 개발사가 각기 다른 사용자 명령을 추가하여 소프트웨어가 호환되지 않고 갈라지는 현상이다.
- **라이선스 ISA(Licensed ISA)**: 비용 지불 계약 없이는 사양 변경이나 하드웨어 코어 제조가 엄격히 금지되는 독점 아키텍처이다.
- **명령 확장 제약(Extension Restriction)**: 권한 소유자의 인가를 받지 않고는 아키텍처에 커스텀 명령어를 임의 추가하지 못하게 하는 제약이다.

</details>

| 비교 항목 | RISC-V | Arm |
|:---|:---|:---|
| 라이선스 모델 | 로열티가 없는 **개방형 ISA 규격** | 고가의 라이선스 비용이 청구되는 **라이선스 ISA** |
| 명령어 확장성 | **사용자 정의 확장** 무제한 구현 | **명령 확장 제약** 존재 |
| 생태계 특성 | **확장 파편화** 가능성 내재 | 정교한 소프트웨어 생태계 및 IP 성숙도 보유 |

#### 한줄 요약

- RISC-V는 커스텀 확장의 자율성과 비용 절감 효과를 제공하며, Arm은 검증된 안정성과 탄탄한 소프트웨어 호환성을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **응용 프로그램 이진 인터페이스(ABI)**: 함수 호출 규칙, 레지스터 사용 약속, 스택 프레임을 정의하는 이진 상호작용 규격이다.
- **차등 테스트(Differential Testing)**: 시뮬레이터와 설계한 하드웨어의 상태 변화를 클록 단위로 상호 대조하는 검증 기법이다.
- **기능 탐지(Feature Detection)**: 소프트웨어가 런타임에 칩의 레지스터를 조회하여 확장 지원 여부를 동적으로 판별하는 기술이다.
- **예약 인코딩(Reserved Encoding)**: 표준을 위해 향후 남겨둔 인코딩 공간으로 커스텀 확장 시 이 공간과 충돌을 피해야 한다.
- **성숙도(Maturity)**: 컴파일러 지원 체계 및 운영체제 반영 여부 등 소프트웨어 환경의 안정성 수준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모듈 확장 난립에 따른 소프트웨어 **확장 파편화** | **응용 프로그램 이진 인터페이스** 고정 및 런타임 **기능 탐지** 적용 | 멀티코어 칩간 소프트웨어 바이너리 호환성 유지 |
| 커스텀 명령어와 표준 **예약 인코딩**의 공간 충돌 | 커스텀 전용 오퍼코드 영역 활용 | 표준 업데이트 시에도 확장 회로의 안전성 확보 |
| 기계어 처리 오작동 및 예외 누수 검증 한계 | 시뮬레이터 기반 **차등 테스트** 및 공식 **적합성 시험** 통과 | 물리적 제작 전 논리 오류 전수 발굴 및 비용 절감 |
| 최신 확장에 대한 컴파일러 툴체인 **성숙도** 부족 | 공식 업스트림 반영 모니터링 및 자체 백엔드 유지보수 | 개발 코드 빌드 실패 사전 차단 |

#### 한줄 요약

- 호환 인터페이스 표준화, 차등 테스트 검증, 예약 영역 준수를 통해 파편화와 물리적 동작 결함을 예방한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Arm IP**: Arm 사가 완제품으로 제공하는 검증된 프로세서 물리 회로 설계 블록이다.
- **구현 방식 선택 기준(Implementation Decision Criteria)**: 연산자 추가, 검증 능력, 기간, 비용을 종합 평가하는 결정 체계이다.

</details>

- 검증 역량과 전용 명령어가 필요하면 **RISC-V**, 빠른 출시와 검증 IP가 우선이면 **Arm IP** 선택

#### 한줄 요약

- 전용 명령 추가와 자체 역량 확보에는 RISC-V, 출시 기간 단축과 기검증된 생태계는 Arm IP를 선택한다.
