## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **제5세대 축소 명령어 집합 컴퓨터(Reduced Instruction Set Computer Five, RISC-V)**: 공개 기본 ISA와 확장을 조합하는 개방형 규격
- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 소프트웨어가 사용할 명령어•레지스터•데이터 형식과 실행 동작을 정의하는 인터페이스
- **개방형 ISA 규격**: 누구나 열람하고 구현할 수 있도록 공개한 명령어 집합 규격
- **사용자 정의 확장**: 전용 연산을 위해 예약 인코딩에 추가하는 명령어 집합

</details>

- 정의/개념: **RISC-V** 는 공개된 기본 명령어 집합에 표준•사용자 정의 확장을 조합하는 **개방형 ISA 규격**
- 배경/필요성: 폐쇄형 ISA는 라이선스와 변경 권한 때문에 **전용 명령•독자 코어 구현이 제약**

#### 한줄 요약

- RISC-V는 공개 ISA를 기반으로 목적에 맞는 명령 확장과 독자 코어 구현을 허용한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **기본 ISA**: RISC-V 구현이 공통으로 제공하는 최소 정수 명령어 집합
- **표준 확장**: 공식 규격으로 정의된 곱셈•부동소수점•벡터 기능
- **마이크로아키텍처(Microarchitecture)**: ISA를 파이프라인•캐시 등의 실제 회로로 구현한 내부 설계

</details>

- 사용료 없는 **개방형 ISA** 로 독자 코어 구현 허용
- **기본 ISA** 에 표준•사용자 정의 확장을 선택 조합
- ISA 공개와 **마이크로아키텍처** 구현 공개의 분리

#### 한줄 요약

- 동일 ISA를 구현해도 파이프라인과 캐시 같은 내부 마이크로아키텍처는 달라질 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **ISA 프로파일**: 필수•선택 확장 조합으로 소프트웨어 호환 목표를 고정한 규격
- **권한 아키텍처(Privileged Architecture)**: 사용자•감독자•머신 모드와 예외•인터럽트 처리 규격
- **XLEN**: 정수 레지스터와 주소 계산에 사용하는 기본 비트 폭
- **공통 실행 계약**: 모든 코어가 동일하게 제공해야 하는 기본 ISA의 명령 동작
- **특권 동작**: 감독자나 머신 모드에서만 허용되는 연산
- **툴체인(Toolchain)**: 소스 코드를 실행 파일로 만드는 컴파일러•어셈블러•링커 도구군
- **바이너리 호환 대상**: 실행 파일이 동작해야 하는 ISA 프로파일•확장 범위

</details>

```text
RISC-V 호환 계약
├─ 기본 ISA
├─ 확장 집합
├─ 권한 아키텍처
└─ 프로파일
```

가지의 의미: 프로파일이 묶는 RISC-V 규격의 정적 구성이다.

| 구성요소 | 책임 |
|:---|:---|
| 기본 ISA | 구현의 **공통 실행 계약** 제공 |
| 확장 집합 | 표준•사용자 정의 **추가 기능** 제공 |
| 권한 아키텍처 | 예외•인터럽트•**특권 동작** 규정 |
| 프로파일 | 툴체인•바이너리 **호환 대상** 고정 |

#### 한줄 요약
- 기본 ISA와 확장•권한 규격을 프로파일로 묶어 소프트웨어가 의존할 호환 범위를 정한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **레지스터 전송 수준(Register Transfer Level, RTL)**: 레지스터 간 데이터 이동과 조합 논리를 클록 단위로 표현하는 설계 모델
- **적합성 시험(Conformance Test)**: 코어가 ISA의 명령•예외•권한 규격대로 동작하는지 확인하는 시험
- **인코딩 계약**: 명령 비트 패턴을 연산•피연산자•확장에 대응시키는 규칙
- **예외 시험**: 비정상 실행이 ISA 규격대로 처리되는지 확인하는 시험
- **권한 시험**: 특권 모드 전환이 ISA 규격대로 처리되는지 확인하는 시험

</details>

```text
1. 프로파일•확장 명세 전달
             │
             ▼
       2. 코어 구현 전달
             │
             ▼
     명령•예외•권한 시험
             ├─ 불일치: 코어 구현 수정
             │          └─ 적합성 재시험
             └─ 통과
                └─ 3. 적합성 통과 정보 전달
                           │
                           ▼
                    툴체인•소프트웨어 적용
```

**동작 원리**

- **1. 프로파일•확장 명세 전달**: XLEN•권한•확장과 구현할 인코딩 계약 제공
- **2. 코어 구현 전달**: ISA 동작을 구현한 RTL 시험
- **3. 적합성 통과 정보 전달**: 명령•예외•권한 시험 결과를 툴체인에 제공

#### 한줄 요약

- 프로파일은 기본 ISA, 확장, 권한 요구사항을 묶어 툴체인과 운영체제가 목표로 삼을 호환 계약을 만든다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **코어 지식재산권(Intellectual Property, IP)**: 검증된 프로세서 코어를 재사용하도록 제공하는 설계 블록
- **Arm**: 라이선스로 ISA와 상용 프로세서 코어 IP를 제공하는 아키텍처 계열
- **확장 파편화**: 구현별 확장 조합 차이로 소프트웨어 호환성이 깨지는 현상

</details>

| 명령어 집합 구조 | RISC-V | Arm |
|:---|:---|:---|
| 적용 기준 | **전용 명령**•자체 검증 역량 | 검증된 **코어 IP**•개발 일정 |
| 핵심 특징 | **개방형 ISA**•사용자 정의 확장 | **라이선스 ISA**•상용 코어 IP |
| 한계 | 구현별 **확장 파편화** | 라이선스 비용•명령 추가 제약 |

> 요약: 확장 자유와 검증 책임을 함께 비교

#### 한줄 요약

- RISC-V는 확장 자유가 크고 Arm 코어 IP는 검증된 구현을 활용해 개발 기간을 줄일 수 있다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **응용 프로그램 이진 인터페이스(Application Binary Interface, ABI)**: 호출 레지스터•스택•바이너리 형식을 정한 호환 규약
- **차등 테스트(Differential Testing)**: 기준 구현과 시험 코어의 실행 결과 차이로 오류를 찾는 시험
- **기능 탐지(Feature Detection)**: 실행 환경의 특정 ISA 확장 지원 여부를 확인하는 절차
- **예약 인코딩**: 향후 표준•사용자 정의 확장을 위해 사용을 제한한 비트 패턴
- **성숙도**: 툴체인과 운영체제가 필요한 기능을 안정적으로 지원하는 정도

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 구현별 확장 조합으로 **바이너리 불일치** | **표준 프로파일•ABI** 고정과 **기능 탐지** | **소프트웨어 호환성** 확보 |
| 사용자 정의 확장과 **표준 인코딩 충돌** | **예약 인코딩•확장 명세** 준수 | 향후 **표준 확장 충돌 방지** |
| 코어의 **ISA 규격 위반** 실행 | **적합성 시험•차등 테스트** 적용 | **구현 정확성** 확보 |
| **툴체인•운영체제 지원** 부족 | 컴파일러•배포판 **성숙도** 사전 검증 | **도입•유지보수 위험** 완화 |
| 맞춤형 가속 코어의 **확장 오류** | **표준 명령•전용 명령** 분리 검증 | **바이너리 호환성** 유지 |

#### 한줄 요약

- 개방형 ISA의 자유는 구현•검증 책임을 동반하므로 프로파일, ABI, 툴체인과 적합성 시험을 함께 관리해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **Arm IP**: Arm ISA를 구현한 검증된 상용 프로세서 코어 설계 블록

</details>

- 전용 명령•검증 역량은 **RISC-V**, 일정 우선은 **Arm IP** 선택

#### 한줄 요약

- 전용 명령과 검증 역량이 있으면 RISC-V를, 검증된 구현과 일정 단축이 우선이면 상용 코어 IP를 검토한다.
