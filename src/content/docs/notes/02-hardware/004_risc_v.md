## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RISC-V**: 공개된 명세에 따라 기본 명령어와 확장을 조합하는 개방형 명령어 집합 구조입니다.
- **개방형 ISA(Open ISA)**: 명세를 공개해 여러 주체가 호환 구현을 개발할 수 있는 ISA 방식입니다.
- **명세 기반 호환성(Specification-Based Compatibility)**: 구현이 달라도 같은 명세의 프로그램 동작을 보장하는 성질입니다.

</details>

- 정의/개념: 공개 명세와 확장 조합을 사용하는 **개방형 ISA**
- 배경/필요성: 공급자 의존도와 특화 프로세서 개발 제약 완화

#### 한줄 요약

- RISC-V는 누구나 같은 명세를 바탕으로 코어를 만들고, 필요한 기능만 확장으로 더할 수 있는 ISA입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 ISA(Base ISA)**: 정수 레지스터와 기본 명령어 동작을 정의하는 공통 규격입니다.
- **표준 확장(Standard Extension)**: 곱셈, 원자 연산, 부동소수점, 벡터처럼 합의된 추가 기능입니다.
- **사용자 정의 확장(Custom Extension)**: 표준 기능과 구분해 제품 특화 연산을 추가하는 확장입니다.

</details>

- 기본 ISA와 표준 확장의 **모듈형 조합**
- 특화 기능을 위한 **사용자 정의 확장**
- 구현 변경에도 유지되는 **명세 기반 호환성**

#### 한줄 요약

- 공통 부분은 표준으로 맞추고, 제품마다 다른 기능은 확장으로 분리해 넣는 방식입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **권한 아키텍처(Privileged Architecture)**: 예외, 인터럽트, 보호 모드의 시스템 동작을 정의하는 규격입니다.
- **제어 및 상태 레지스터(Control and Status Register, CSR)**: 권한 상태, 예외 원인, 제어 값을 보관하는 레지스터입니다.
- **ISA 프로파일(ISA Profile)**: 특정 운영체제나 생태계에 필요한 확장 조합을 정한 호환 기준입니다.

</details>

```text
[RISC-V 명세]
├─ 기본 ISA
├─ 표준 확장
├─ 사용자 정의 확장
├─ 권한 아키텍처
└─ ISA 프로파일
```

| 구성요소 | 책임 |
|:---|:---|
| 기본 ISA | 공통 명령어와 레지스터 동작 규정 |
| 표준 확장 | 범용 기능의 호환 명령어 제공 |
| 사용자 정의 확장 | 도메인 특화 연산 추가 |
| 권한 아키텍처 | 예외·인터럽트·CSR 동작 규정 |
| ISA 프로파일 | 목표 소프트웨어의 확장 범위 고정 |

#### 한줄 요약

- 기본 ISA가 공통 뼈대라면, 확장과 권한 규격, 프로파일은 어떤 시스템까지 호환할지 정하는 세부 약속입니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **레지스터 전송 수준(Register-Transfer Level, RTL)**: 레지스터 사이 데이터 이동과 논리 연산으로 회로를 표현하는 설계 수준입니다.
- **적합성 시험(Compliance Test)**: 구현이 ISA 명세의 명령어와 예외 동작을 지키는지 확인하는 시험입니다.
- **차등 시험(Differential Testing)**: 참조 구현과 대상 구현의 실행 결과를 같은 입력으로 비교하는 검증입니다.

</details>

```text
[1. 요구 기능 확정]
          │
          ▼
[2. ISA·확장 조합]
          │
          ▼
[3. RTL 구현]
          │
          ▼
[4. 적합성·차등 시험]
```

동작 원리:

1. 요구 기능 확정: 운영체제, 성능, 전력 요구의 범위 설정
2. ISA·확장 조합: 기본 ISA와 필요한 표준 확장 선택
3. RTL 구현: 명령어, 권한 상태, 예외 동작의 회로 반영
4. 적합성·차등 시험: 명세와 참조 구현의 결과 일치 확인

#### 한줄 요약

- RISC-V 코어는 먼저 지원할 기능을 정하고, 그 약속대로 회로를 만든 뒤 표준 동작과 비교해 검증합니다.

## Ⅴ. 종류 및 비교

| 확장 유형 | 표준 확장 | 사용자 정의 확장 |
|:---|:---|:---|
| 적용 기준 | 여러 구현에서 공통 기능 필요 | 특정 제품의 특화 기능 필요 |
| 핵심 특징 | 명세·도구·바이너리 호환성 공유 | 목적에 맞는 연산과 데이터 경로 추가 |
| 한계 | 기능 구성과 변경의 제약 | 이식성·도구 지원·검증 부담 |

#### 한줄 요약

- 여러 제품에서 함께 쓸 기능은 표준 확장에 두고, 한 제품에서만 필요한 기능은 사용자 정의 확장에 둡니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **응용 프로그램 이진 인터페이스(Application Binary Interface, ABI)**: 컴파일된 코드가 운영체제와 라이브러리에서 지키는 호출·데이터 규약입니다.
- **예약 인코딩(Reserved Encoding)**: 미래 표준화나 지정 용도를 위해 임의 사용을 금지한 명령어 비트 패턴입니다.
- **기능 탐지(Feature Discovery)**: 실행 환경에서 지원하는 확장을 확인해 코드 경로를 정하는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 구현별 확장 차이로 바이너리 실행 실패 | ABI·프로파일 고정과 기능 탐지 적용 | 배포 대상과 실행 조건 명확화 |
| 특화 명령이 표준 인코딩과 충돌 | 사용자 정의 공간 사용과 예약 인코딩 회피 | 향후 표준 확장과의 충돌 방지 |
| 예외 처리 구현이 명세와 불일치 | 적합성 시험과 차등 시험 자동화 | 규격 오류 조기 발견 |
| 확장용 컴파일러 지원 범위 불명확 | 도구 버전 고정과 빌드 시험 적용 | 개발 환경 재현성과 이식성 확보 |

#### 한줄 요약

- 확장 자체보다 확장이 다른 구현과 충돌하지 않고 도구와 프로그램에서 정확히 동작하는지를 먼저 관리해야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **소프트웨어 생태계(Software Ecosystem)**: 운영체제, 컴파일러, 라이브러리, 개발 도구가 함께 제공하는 실행 환경입니다.

</details>

- 특화 연산과 구현 자율성이 우선이면 **RISC-V**를 선택하고, 확장 호환성·검증 역량·**소프트웨어 생태계**를 프로파일 기준으로 함께 확정

#### 한줄 요약

- RISC-V는 명세가 열려 있다는 장점만으로 고르는 것이 아니라, 필요한 확장과 이를 뒷받침할 도구·검증 체계를 갖출 때 선택합니다.
