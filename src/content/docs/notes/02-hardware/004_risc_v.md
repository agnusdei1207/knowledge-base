## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RISC-V**: 오픈 표준 라이선스 기반으로 기본 정수 명령어 세트(Base ISA)와 모듈형 표준/커스텀 확장을 제공하는 로열티 프리 개방형 명령어 집합 구조.
- **개방형 ISA(Open Standard ISA)**: 공개 명세를 로열티 없이 구현하고 특화 기능을 확장할 수 있는 표준 규격.
- **명세 기반 호환성(Specification-Based Compatibility)**: 마이크로아키텍처의 세부 물리 구현과 무관하게 공식 ISA 명세를 준수하여 동일 바이너리의 상호 운용성을 보장하는 성질.

</details>

- 정의/개념: 고정된 최소 기본 정수 세트(Base ISA) 위에 선택적 표준 및 커스텀 모듈을 결합하여 로열티 없이 도메인 특화 프로세서를 구성할 수 있는 **개방형 ISA** 규격
- 배경/필요성: 독점 상용 ISA의 고액 라이선스 비용과 벤더 종속성, 도메인 특화 가속 명령어의 임의 확장 불가 한계를 극복하기 위한 오픈 표준 하드웨어 생태계 태동

#### 한줄 요약
- RISC-V의 본질은 로열티 절감을 넘어 설계자가 원하는 도메인 특화 명령어를 하드웨어에 직접 추가할 수 있는 아키텍처 자율성이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 ISA(Base ISA)**: 정수 연산 및 기본 분기 제어를 정의하여 모든 RISC-V 하드웨어가 반드시 준수해야 하는 고정 불변의 최소 필수 세트(RV32I/RV64I).
- **표준 확장(Standard Extension)**: 공식 표준화 위원회의 승인을 받아 Opcode가 배정된 모듈형 확장 세트(M: 곱셈/나눗셈, A: 원자적 연산, F/D: 부동소수점, C: 압축, V: 벡터).
- **사용자 정의 확장(Custom Extension)**: 표준 인코딩과 충돌하지 않도록 사전에 비워둔 커스텀 예약 공간(Custom Opcode)을 활용하여 독자 가속 회로를 구현하는 확장.

</details>

- 최소주의와 모듈성: 불변의 **기본 ISA** 위에 필요한 **표준 확장**만 선택 결합하여 칩 면적과 정적 전력 소모 최소화
- 충돌 없는 커스텀 확장: 사전에 예약된 독립 인코딩 공간을 통해 독자적인 **사용자 정의 확장**을 추가해도 표준 명령어 체계와의 충돌 방지
- 에코시스템 호환성: **명세 기반 호환성**을 확보하여 오픈소스 GCC/LLVM 툴체인 및 Linux/FreeRTOS 운영체제 생태계 즉시 활용

#### 한줄 요약
- 기본 정수 세트는 절대 변하지 않고 필요한 확장만 레고 블록처럼 끼워 맞추는 모듈형 설계로 파편화를 억제하면서 특화 가속을 구현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **권한 아키텍처(Privileged Architecture)**: User(U-mode: 사용자 앱), Supervisor(S-mode: OS 커널), Machine(M-mode: 하드웨어 제어/펌웨어)의 3단계 실행 특권 계층을 규정한 시스템 명세.
- **제어 및 상태 레지스터(Control and Status Register, CSR)**: 프로세서 동작 모드 전환, 인터럽트 인에이블, 가상 메모리 페이징 활성화(satp), 성능 카운터를 제어하는 시스템 특수 레지스터.
- **ISA 프로파일(ISA Profile)**: 특정 OS 실행에 필요한 필수 표준 확장의 조합을 표준화하여 소프트웨어 배포 바이너리 호환성을 보장하는 공식 규격.

</details>

```text
+-----------------------------------------------------------------------+
| RISC-V 표준 명세 아키텍처 체계                                        |
|  +-----------------------------------------------------------------+  |
|  | 권한 아키텍처 계층 (Privilege Mode & CSR)                       |  |
|  |  - M-Mode (머신 모드): 펌웨어/부트로더, 물리 하드웨어 직접 제어 |  |
|  |  - S-Mode (수퍼바이저 모드): OS 커널, 가상 메모리 관리(satp)   |  |
|  |  - U-Mode (유저 모드): 사용자 공간 애플리케이션 격리 실행       |  |
|  +--------------------------------+--------------------------------+  |
|                                   | 명령어 실행 특권 통제             |
|  +--------------------------------v--------------------------------+  |
|  | 명령어 집합 구조 (Base ISA & Extensions)                        |  |
|  |  +-----------------------------------------------------------+  |  |
|  |  | 기본 정수 세트 (Base ISA: RV32I / RV64I 불변 코어 규격)      |  |  |
|  |  +-----------------------------------------------------------+  |  |
|  |  +-----------------------------+-----------------------------+  |  |
|  |  | 공식 표준 확장 (M, A, F, D, V)| 사용자 정의 확장 (Custom-0~3)|  |  |
|  |  +-----------------------------+-----------------------------+  |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

선의 의미: `+---+`는 명세 체계 및 모듈 경계, `->`는 권한 계층과 명령어 세트 간 실행 통제 관계

| 구성요소 | 책임 |
|:---|:---|
| 기본 ISA | 정수 연산, 로드/스토어, 기본 제어 흐름을 규정하는 **불변 코어 명세** |
| 표준 확장 | 부동소수점(F/D), 원자적 연산(A), 벡터(V) 등 **공통 가속 규격** 제공 |
| 사용자 정의 확장 | 예약 Opcode 공간을 통한 **도메인 특화 가속기** 제어 명령어 구현 |
| 권한 아키텍처 | U/S/M 3단계 모드와 **CSR** 레지스터를 통한 하드웨어 격리 및 예외 제어 |
| ISA 프로파일 | 애플리케이션(RVA) 및 마이크로컨트롤러(RVM)용 **바이너리 호환성** 규약 제공 |

#### 한줄 요약
- RISC-V는 기본 정수 세트 위에 표준/커스텀 확장을 올리고, 3단계 권한 모델과 ISA 프로파일을 통해 시스템 안정성과 소프트웨어 호환성을 확보한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **적합성 시험(Compliance Test)**: 하드웨어 코어가 공식 RISC-V 명세의 명령어 동작, CSR 상태 변화, 예외 처리를 정확히 준수하는지 검증하는 공식 테스트.
- **차등 시험(Differential Testing)**: Spike 같은 참조 모델과 RTL에 동일 입력을 주어 아키텍처 상태를 대조하는 검증 기법.

</details>

```text
[1. 워크로드 요구사항 분석 (임베디드 vs 범용 서버)]
                        │
                        ▼
           2. ISA 모듈 조합 및 확장 결정
             ┌──────────┴──────────┐
    (표준 프로파일 채택)         (사용자 정의 확장 결합)
             │                             │
             │ (RVA22 = RV64GCBK)          ▼
             │               예약된 Custom Opcode 인코딩 검증
             └──────────┬──────────────────┘
                        │
                        ▼
3. RTL 하드웨어 설계 및 프로세서 파이프라인 구현
                        │
                        ▼
4. 적합성 시험 및 차등 시험(Differential Testing) 수행
             ┌──────────┴──────────┐
      [ 불일치 발생 ]               [ 전수 통과 ]
             │                             │
             ▼                             ▼
    RTL 결함 수정 후 재검증        표준 프로파일 선언 및 OS 배포
```

분기 결과: **표준 확장**은 기존 오픈소스 컴파일러 생태계를 즉시 활용하며, **사용자 정의 확장**은 도메인 가속을 달성하되 독자 툴체인 패치가 수반됨

**동작 원리**

1. **워크로드 요구사항 분석**: 타깃 시스템 환경(초저전력 마이크로컨트롤러 vs 고성능 Linux 서버)의 처리량과 소비 전력 요구조건을 정의함
2. **ISA 모듈 조합 및 확장 결정**: 범용 OS 구동용 표준 프로파일(RVA)을 선정하거나 특화 연산 가속을 위한 사용자 정의 확장을 배정함
3. **RTL 하드웨어 설계 및 프로세서 파이프라인 구현**: 선정된 명령어 집합에 맞추어 데이터패스, 제어 로직, CSR 및 실행 파이프라인을 RTL로 합성함
4. **적합성 시험 및 차등 시험 수행**: 공식 컴플라이언스 슈트와 Spike 참조 모델 기반 차등 시험을 수행하여 아키텍처 상태 전이 결함을 검증함

#### 한줄 요약
- RISC-V 프로세서 개발은 모듈 선택 ➔ 커스텀 확장 설계 ➔ RTL 구현 ➔ 차등 시험 검증 ➔ 툴체인 연동의 표준화된 파이프라인을 거친다.

## Ⅴ. 종류 및 비교

| RISC-V 확장 구분 | 표준 확장 | 사용자 정의 확장 |
|:---|:---|:---|
| 적용 기준 | **공통 컴파일러 생태계** 및 범용 OS 활용 필수 시 | **도메인 특화 하드웨어 가속**(AI/DSP/보안) 구현 시 |
| 핵심 특징 | 공식 Opcode 배정 및 표준 커뮤니티 승인 | 사전에 예약된 **독립 Opcode 공간** 활용 |
| 한계 | 신규 표준 제정까지 긴 승인 기간 소요 | 독자 툴체인 유지보수 부담 및 타 벤더 구현체와의 비호환 |

#### 한줄 요약
- 범용 소프트웨어 호환성이 우선이면 표준 확장을 조합하고, 극한의 전력 대 성능비 가속이 필요하면 사용자 정의 확장을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **기능 탐지(Feature Discovery)**: 소프트웨어가 런타임에 CSR(misa 등) 또는 디바이스 트리(Device Tree)를 조회하여 현재 하드웨어가 지원하는 ISA 확장을 동적으로 판별하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 반도체 제조사별 확장 조합 상이로 인한 소프트웨어 파편화 | **ISA 프로파일(RVA22/RVA23)** 준수 및 **기능 탐지** 적용 | 공통 배포 바이너리의 상호 운용성 확보 |
| 커스텀 명령어가 향후 제정될 신규 표준 Opcode와 충돌 | 예약 인코딩 영역(Custom-0~3) 엄격 준수 | 표준 발전 시에도 하드웨어 재설계 오버헤드 원천 방지 |
| 마이크로아키텍처의 예외 및 CSR 동작이 명세와 미세 불일치 | **적합성 시험** 및 **차등 시험** 파이프라인 자동화 | OS 부팅 단계의 시스템 패닉 및 상태 오류 사전 차단 |

#### 한줄 요약
- RISC-V 실무 도입 시에는 프로파일 기반의 파편화 통제와 예약 인코딩 준수, 그리고 철저한 차등 시험 검증 체계 구축이 필수적이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **칩렛(Chiplet)**: 단일 모놀리식 다이 대신 기능별로 분할 제조한 소형 다이를 고속 인터커넥트로 결합하여 하나의 패키지에 집적하는 이기종 반도체 설계 방식.

</details>

- 초저전력 임베디드부터 데이터센터·AI 가속까지 생태계가 확장되는 성장 단계에 위치하며, 차세대 이기종 컴퓨팅에서는 RVA22/RVA23 표준 프로파일을 중심으로 **칩렛** 인터페이스와 결합하는 개방형 반도체 플랫폼으로 진화하고 있어, 커스텀 가속 명령어 추가에 따른 툴체인 포킹 비용과 상용 바이너리 호환성 간 트레이드오프를 평가한 확장 범위 설계

#### 한줄 요약
- RISC-V는 개방성과 모듈성을 통해 특화 가속 반도체 시장을 주도하고 있으며, 프로파일 준수와 검증 자동화가 성공적인 도입의 핵심이다.
