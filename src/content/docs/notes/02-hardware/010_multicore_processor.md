## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티코어 프로세서(Multicore Processor)**: 단일 반도체 칩(Die) 내에 둘 이상의 독립적인 실행 코어를 집적하여 스레드 수준 병렬성을 처리하는 프로세서.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 여러 독립적인 소프트웨어 실행 흐름(Thread)을 다중 코어에 분산하여 동시에 병렬 실행하는 기법.
- **전력 장벽(Power Wall)**: 클록 주파수와 공급 전압의 증가에 따라 전력 소모 및 발열이 지수적으로 증가하여 단일 코어 성능 향상이 물리적 한계에 부딪히는 현상.

</details>

- 정의/개념: 단일 다이에 독립 실행 코어를 여럿 집적해 **스레드 수준 병렬성(TLP)** 기반 성능을 확보하는 **멀티코어 프로세서**
- 배경/필요성: 주파수와 전압을 올리면 전력이 그보다 빠르게 증가하는 **전력 장벽**에 막혀 단일 코어 확장이 중단됨

#### 한줄 요약
- 멀티코어는 더 나은 설계여서 선택된 것이 아니라 주파수를 올릴 길이 막혀 남은 유일한 방향이었고, 그래서 성능 책임이 하드웨어에서 소프트웨어로 넘어갔다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law)**: 시스템의 병렬화 가능한 코어 수를 아무리 늘려도 프로그램 내 직렬(Sequential) 실행 구간의 비율에 의해 전체 가속비(Speedup) 상한이 제한된다는 법칙.
- **캐시 일관성(Cache Coherence)**: 멀티코어 환경에서 각 코어의 사설 캐시에 저장된 동일 메모리 주소의 데이터 사본들이 항상 일치하는 정합성을 유지하도록 보장하는 하드웨어 규약.
- **인터커넥트(Interconnect)**: 다중 코어, 캐시 계층, 메모리 제어기 간에 데이터와 일관성 제어 메시지를 고속으로 중계하는 온칩 네트워크(On-Chip Network) 통신망.

</details>

- 독립 스레드를 여러 코어에 배치해 단위 시간당 완료 스레드 수 증대
- 직렬 실행 비율이 남으면 **암달의 법칙**에 따라 전체 가속비 제한
- 사설 캐시 사이의 동일 주소 갱신 시 **캐시 일관성** 프로토콜로 정확성 보장 필요
- 코어·LLC·메모리 간 **인터커넥트** 대역폭이 확장 가속비의 병목

#### 한줄 요약
- **암달의 법칙** 코어를 늘려도 넘을 수 없는 상한을 정하고 **캐시 일관성** 비용은 그 상한에 닿기도 전에 이득을 깎으므로, 실제 한계는 이론값보다 훨씬 앞에 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 캐시(Private Cache)**: 특정 개별 코어에 전용으로 할당되어 해당 코어만 독점적으로 접근하는 저지연 L1/L2 캐시.
- **최종 단계 캐시(Last-Level Cache, LLC)**: 온칩 캐시 계층 구조의 최하단에 위치하여 모든 코어가 공유하며 메인 메모리 접근 트래픽을 완충하는 대용량 L3/L4 캐시.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 프로세서 다이 내부에 직접 집적되어 외부 DRAM 채널과의 데이터 송수신 및 메모리 요청 스케줄링을 제어하는 고속 메모리 컨트롤러.

</details>

```text
[멀티코어 칩]
  코어 0 ── 사설 캐시 ─┐
  코어 1 ── 사설 캐시 ─┼─ 인터커넥트 ── 공유 LLC ── IMC
          ···          ┘                         │
                                               메인 메모리
```

선의 의미: `──`는 데이터·일관성 메시지 전송 경로, 묶음은 코어별 사설 캐시의 공유 경로 합류

| 구성요소 | 책임 |
|:---|:---|
| 코어 클러스터 | 스레드별 명령어 실행·레지스터 상태 보관 |
| 사설 캐시 | 코어 전용 고속 데이터·명령어 제공 |
| **인터커넥트** | **캐시 일관성** 메시지·공유 데이터 전달 |
| LLC | 코어 간 공유 데이터 완충·메모리 접근 감소 |
| IMC | 메모리 채널 요청 스케줄링·대역폭 관리 |

#### 한줄 요약
- 코어는 복제하면 늘지만 **인터커넥트** 및 **IMC**는 공유 자원이라 복제되지 않으므로, 코어 수가 늘수록 병목은 반드시 공유 쪽으로 이동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **쓰기 소유권(Write Ownership)**: 캐시 일관성 프로토콜에서 특정 캐시 라인을 수정하기 위해 해당 코어가 단독으로 확보해야 하는 배타적 수정 권한.
- **무효화(Invalidation)**: 특정 코어가 공유 캐시 라인을 수정할 때 다른 코어들의 사설 캐시에 존재하는 동일 주소 사본을 무효(Invalid) 상태로 변경하여 오래된 값의 참조를 차단하는 동작.

</details>

```text
코어A: 공유 주소 쓰기 요청
          │
          ▼
쓰기 소유권 확인
          │
     ┌────┴──────────────────┐
     │                       │
소유권 없음                 독점 소유
     │                       │
     ▼                       ▼
1. 인터커넥트 소유권 요청      → 쓰기 수행
     │
     ▼
2. 타 코어 캐시 라인 무효화 (인터커넥트 브로드캐스트)
     │
     ▼
3. 소유권 획득 및 쓰기 수행
```

분기 결과: 사본을 이미 독점했으면 쓰기가 코어 안에서 끝나지만, 공유 중이면 **무효화가** 완료될 때까지 쓰기가 인터커넥트 왕복 시간에 묶임

#### 한줄 요약
- 같은 쓰기 명령이라도 그 데이터를 몇 개 코어가 함께 보고 있었느냐에 따라 비용이 수십 배 갈리며, 공유 변수 하나가 병렬 프로그램을 무너뜨리는 이유가 여기에 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대칭 다중 처리(Symmetric Multiprocessing, SMP)**: 동일한 구조와 성능을 갖는 복수의 프로세서 코어가 단일 메모리 공간과 OS를 대칭적으로 공유하는 멀티프로세싱 아키텍처.
- **이종 멀티코어(Heterogeneous Multicore)**: 고성능 대형 코어(Big Core)와 저전력 고효율 코어(LITTLE Core)를 단일 칩에 혼합 집적하여 워크로드 특성에 따라 동적으로 작업을 분배하는 아키텍처.
- **동시 멀티스레딩(Simultaneous Multithreading, SMT)**: 단일 물리 코어 내에서 복수의 하드웨어 스레드 문맥(Context)을 유지하며 파이프라인 실행 유닛을 매 사이클마다 공유하여 활용률을 극대화하는 기술(Intel Hyper-Threading 등).

</details>

| 병렬 실행 구조 | SMP | 이종 멀티코어 | SMT |
|:---|:---|:---|:---|
| 적용 기준 | 균일한 작업 유형·단순 코어 확장 | 작업 유형별 성능·전력 요구 차이 | 단일 코어의 유휴 실행 자원 활용 |
| 핵심 특징 | 동등 코어의 균등 **TLP** 분산 | 고성능·고효율 코어 혼합 배치 | 한 코어 안의 다중 하드웨어 스레드 |
| 한계 | 공유 LLC·**인터커넥트** 경합 | 스케줄링·이종 코어 이전 비용 | 실행 유닛·사설 캐시 간섭 |

#### 한줄 요약
- **SMT**만은 코어를 늘리지 않고 병렬성을 얻으므로 면적 대비 효과가 가장 크지만, 실행 자원을 나눠 쓰는 만큼 스레드 하나의 성능은 오히려 떨어진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 논리적으로 독립된 변수를 갱신하지만 해당 변수들이 우연히 동일한 물리 캐시 라인에 위치하여 불필요한 캐시 무효화 트래픽이 유발되는 현상.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립적인 전역 변수나 데이터 구조체 사이에 더미 바이트를 삽입하여 서로 다른 캐시 라인으로 분리 배치함으로써 거짓 공유를 방지하는 프로그래밍 기법.
- **비균일 메모리 접근(Non-Uniform Memory Access, NUMA)**: 각 프로세서 소켓마다 로컬 메모리를 분할 배치하여 로컬 메모리와 원격 소켓 메모리 간의 접근 지연시간 및 대역폭이 불균일한 다중 소켓 아키텍처.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 갱신인데 캐시 라인 공유로 **거짓 공유** 발생 | **캐시 라인 패딩**·데이터 구조 재배치 | 불필요한 일관성 트래픽 감소 |
| 코어별 작업량 차이로 유휴 코어 발생 | 작업 훔치기·동적 부하 분산 적용 | 병렬 구간 코어 활용률 향상 |
| **NUMA** 원격 메모리 접근 지연 증가 | 스레드·메모리의 NUMA 인지 배치 | 원격 지연·대역폭 경합 완화 |
| 이종 코어에 작업 성격 불일치 | 성능·전력 힌트 기반 코어 배치 | 작업별 에너지 효율 향상 |

#### 한줄 요약
- 네 대책이 모두 배치 문제로 귀결되는 것은 멀티코어의 병목이 연산 지연이 아닌 코어 간 데이터 이동 거리에서 발생하기 때문

## Ⅶ. 결론

- 병렬 비율과 일관성·메모리 경합을 먼저 측정해 코어 수를 확장하되, 가속비가 포화되면 코어 추가 대신 직렬 구간 단축과 공유 데이터 재배치를 우선 적용

#### 한줄 요약
- 코어를 더 살 것인지는 하드웨어 결정처럼 보이지만 실제로는 코드의 직렬 비율이 이미 답을 정해 두었고, 그 비율을 모른 채 늘린 코어는 전력만 쓴다.
