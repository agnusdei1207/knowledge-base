## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티코어 프로세서(Multicore Processor)**: 하나의 칩에 둘 이상의 독립 실행 코어를 집적한 프로세서입니다.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 독립 소프트웨어 스레드를 동시에 실행할 수 있는 병렬성입니다.
- **전력 장벽(Power Wall)**: 주파수와 전압 증가가 전력 소모와 발열로 제한되는 현상입니다.

</details>

- 정의/개념: 여러 실행 코어로 스레드를 병렬 처리하는 **TLP 확장 구조**
- 배경/필요성: 단일 코어의 전력 장벽과 병렬 작업 처리량 제약 완화

#### 한줄 요약

- 멀티코어는 한 코어의 속도를 끝없이 높이는 대신, 여러 코어가 각자 다른 일을 맡도록 해 전체 작업량을 늘리는 방식입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law)**: 병렬화할 수 없는 직렬 구간이 전체 가속비의 상한을 정한다는 법칙입니다.
- **캐시 일관성(Cache Coherence)**: 여러 캐시의 같은 메모리 위치가 읽기·쓰기에서 올바른 값을 보이게 하는 성질입니다.
- **인터커넥트(Interconnect)**: 코어, 캐시, 메모리 제어기 사이의 데이터와 제어 메시지 연결망입니다.

</details>

- 단일 지연보다 다중 작업의 **전체 처리량 확장**
- 직렬 구간에 제한되는 **암달의 법칙**
- 공유 데이터에서 필요한 **캐시 일관성**

#### 한줄 요약

- 코어를 늘리면 동시에 할 수 있는 일은 많아지지만, 순서대로 해야 하는 일과 함께 쓰는 메모리는 여전히 전체 속도를 제한합니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 캐시(Private Cache)**: 특정 코어가 가까이에서 사용하는 캐시입니다.
- **최종 단계 캐시(Last-Level Cache, LLC)**: 메인 메모리 앞의 마지막 캐시 계층입니다.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 프로세서 안에서 메모리 채널 요청을 관리하는 제어기입니다.

</details>

```text
[멀티코어 칩]
├─ 코어 클러스터
├─ 사설 캐시
├─ 인터커넥트
├─ LLC
└─ IMC
```

| 구성요소 | 책임 |
|:---|:---|
| 코어 클러스터 | 스레드별 명령어 실행 |
| 사설 캐시 | 코어 가까운 데이터와 명령어 제공 |
| 인터커넥트 | 일관성 메시지와 공유 데이터 전달 |
| LLC | 공유 데이터와 메모리 접근 완충 |
| IMC | 메모리 채널 요청과 대역폭 관리 |

#### 한줄 요약

- 멀티코어 칩은 코어만 여러 개인 구조가 아니라, 각 코어의 빠른 캐시와 모두가 만나는 캐시·메모리 길을 함께 갖춘 구조입니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **쓰기 소유권(Write Ownership)**: 캐시 라인을 수정하기 전에 특정 코어가 확보해야 하는 쓰기 권한입니다.
- **무효화(Invalidation)**: 다른 캐시의 이전 사본을 더 이상 사용하지 못하게 하는 처리입니다.

</details>

```text
[1. 코어의 쓰기 요청]
          │
          ▼
[2. 사설 캐시 상태 확인]
          │
          ▼
[3. 소유권 획득과 사본 무효화]
          │
          ▼
[4. 로컬 데이터 갱신]
```

동작 원리:

1. 코어의 쓰기 요청: 대상 데이터 수정 명령어 실행
2. 사설 캐시 상태 확인: 데이터 존재와 쓰기 권한 확인
3. 소유권 획득과 사본 무효화: 인터커넥트로 다른 코어 사본 조정
4. 로컬 데이터 갱신: 쓰기 가능한 사본에 변경 값 기록

#### 한줄 요약

- 여러 코어가 같은 데이터를 캐시에 들고 있으면, 한 코어가 쓰기 전에 다른 코어의 오래된 사본을 못 쓰게 해야 모두 같은 결과를 봅니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대칭 다중 처리(Symmetric Multiprocessing, SMP)**: 동등한 코어에 운영체제가 스레드를 대칭적으로 배치하는 방식입니다.
- **이종 멀티코어(Heterogeneous Multicore)**: 성능과 전력 특성이 다른 코어를 한 시스템에 함께 두는 구조입니다.
- **동시 멀티스레딩(Simultaneous Multithreading, SMT)**: 한 물리 코어가 여러 하드웨어 스레드의 상태를 유지하며 실행 자원을 공유하는 방식입니다.

</details>

| 병렬 실행 구조 | SMP | 이종 멀티코어 | SMT |
|:---|:---|:---|:---|
| 적용 기준 | 균일 작업의 단순한 확장 | 작업별 성능·전력 요구 차이 | 코어 유휴 자원 활용 필요 |
| 핵심 특징 | 동등 코어의 스레드 분산 | 고성능·고효율 코어의 혼합 | 한 코어 안의 다중 스레드 |
| 한계 | 공유 캐시·메모리 경합 | 스케줄링과 이전 비용 | 실행 유닛·캐시 간섭 |

#### 한줄 요약

- 같은 코어를 많이 쓰면 SMP, 성격이 다른 코어를 섞으면 이종 멀티코어, 한 코어의 빈 시간을 다른 스레드가 쓰면 SMT입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 데이터가 같은 캐시 라인에 있어 독립 갱신에도 일관성 트래픽이 생기는 현상입니다.
- **캐시 라인 패딩(Cache-Line Padding)**: 자주 갱신하는 독립 데이터를 서로 다른 캐시 라인에 배치하는 기법입니다.
- **비균일 메모리 접근(Non-Uniform Memory Access, NUMA)**: 메모리 위치에 따라 접근 지연과 대역폭이 달라지는 구조입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 갱신인데 캐시 라인 공유로 트래픽 발생 | 캐시 라인 패딩과 데이터 구조 재배치 | 불필요한 일관성 메시지 감소 |
| 코어별 작업량 차이로 유휴 코어 발생 | 작업 훔치기와 부하 분산 적용 | 병렬 구간의 코어 활용률 향상 |
| NUMA 원격 메모리 접근 지연 | 스레드·메모리의 NUMA 인지 배치 | 원격 지연과 대역폭 경합 완화 |
| 이종 코어에 작업 성격이 맞지 않음 | 성능·지연·전력 힌트 기반 배치 | 작업별 에너지 효율 향상 |

#### 한줄 요약

- 멀티코어 성능은 코어 수보다 데이터를 어디에 놓고 작업을 어느 코어에 보내며 공유를 얼마나 줄이는지에서 크게 달라집니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **메모리 대역폭(Memory Bandwidth)**: 단위 시간에 메모리와 프로세서 사이에서 전송할 수 있는 데이터의 양입니다.

</details>

- 병렬 비율이 높고 **메모리 대역폭**·일관성 비용을 통제할 수 있으면 멀티코어를 확장하고, 직렬 구간이 우세하면 코어 수보다 알고리즘 분할과 부하 배치부터 개선

#### 한줄 요약

- 멀티코어는 코어 수 경쟁이 아니라, 프로그램의 병렬 비율과 공유 데이터 비용이 추가 코어의 이득보다 작은지 확인하는 설계 선택입니다.
