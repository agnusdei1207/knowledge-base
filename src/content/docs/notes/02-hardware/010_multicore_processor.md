## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티코어 프로세서(Multicore Processor)**: 단일 반도체 칩(Die) 내에 둘 이상의 독립적인 실행 코어를 집적하여 스레드 수준 병렬성(TLP)을 처리하는 마이크로프로세서.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 복수의 독립적인 소프트웨어 실행 흐름(Thread)을 다중 코어에 분산 배치하여 동시에 병렬 실행하는 기법.
- **전력 장벽(Power Wall)**: 단일 코어의 클록 주파수와 전압을 높일 때 전력 소모와 발열이 지수적으로 증가하여 주파수 증대를 통한 성능 향상이 한계에 도달한 현상.

</details>

- 정의/개념: 단일 반도체 다이에 독립된 복수의 연산 코어를 집적하여 **스레드 수준 병렬성(TLP)**을 통해 시스템 전체 처리량을 확장하는 **멀티코어 프로세서 아키텍처**
- 배경/필요성: 단일 코어의 클록 주파수 상승에 따른 **전력 장벽** 및 **발열 한계** 극복

#### 한줄 요약
- 멀티코어는 단일 코어의 주파수 증대 한계를 극복하기 위해 코어를 복제하여 병렬 처리량을 확장하는 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law)**: 병렬 프로세서 코어 수를 무한히 늘려도 프로그램 내 직렬(Sequential) 실행 구간의 비율에 의해 전체 시스템 가속비(Speedup) 상한이 제한된다는 법칙.
- **캐시 일관성(Cache Coherence)**: 각 코어의 사설 캐시에 분산된 동일 메모리 주소 데이터 사본들이 항상 일치하는 최신 정합성을 유지하도록 보장하는 하드웨어 규약.
- **온칩 인터커넥트(On-Chip Interconnect)**: 다중 코어, 사설 캐시, 공유 LLC, 통합 메모리 제어기 간에 데이터와 일관성 메시지를 고속 중계하는 내부 통신 네트워크(Ring, Mesh 등).

</details>

- 처리량 확장: 다중 코어에 독립 스레드를 분산 배치하여 클록 주파수 상승 없이도 총 연산 처리량 대폭 증대
- 가속비의 한계: 프로그램 내 병렬화 불가능한 직렬 구간 비율에 따라 **암달의 법칙**에 의해 성능 가속비 상한 제약
- 공유 자원 정합성: 다중 코어가 동일 주소를 갱신할 때 발생하는 데이터 불일치를 방지하기 위해 하드웨어 **캐시 일관성** 프로토콜(MESI/MOESI) 필수
- 인터커넥트 병목: 코어 수가 증가함에 따라 **온칩 인터커넥트** 및 메모리 제어기 대역폭이 시스템 확장의 핵심 병목으로 부상

#### 한줄 요약
- 멀티코어 성능은 암달의 법칙에 의한 직렬 구간 비율과 캐시 일관성 인터커넥트 대역폭에 의해 결정된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 캐시(Private Cache)**: 개별 코어에 전용으로 할당되어 해당 코어만 독점 접근하는 초저지연 L1/L2 캐시.
- **최종 단계 캐시(Last-Level Cache, LLC)**: 온칩 캐시 계층의 최하단에 위치하여 모든 코어가 공유하며 DRAM 접근을 완충하는 대용량 L3 캐시.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 프로세서 다이에 내장되어 다중 DDR 메모리 채널과의 통신을 직접 제어하는 고속 컨트롤러.

</details>

```text
멀티코어 프로세서 하드웨어 구조
├── 실행 계층 (개별 CPU 코어 0~N)
├── 사설 저장 계층 (코어별 L1 I/D 및 L2 캐시)
├── 통신 계층 (온칩 고속 인터커넥트 Ring/Mesh)
├── 공유 저장 계층 (공유 최종 단계 캐시 LLC/L3)
└── 메모리 제어 계층 (통합 메모리 제어기 IMC)
```

선의 의미: 가지(`├──`, `└──`)는 코어 실행부부터 메모리 인터페이스까지의 계층 구성을 나타냄

| 계층/유닛 | 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| 실행 계층 | 개별 CPU 코어들 | 독립 소프트웨어 스레드 명령어 인출·실행 | 코어별 독립 레지스터/실행유닛 |
| 사설 저장 계층 | L1 I/D, L2 캐시 | 해당 코어 전용 초고속 데이터 및 명령어 캐싱 | 코어 전용 초저지연 (수 사이클) |
| 통신 계층 | 온칩 인터커넥트 | 코어 간 데이터 전송 및 **캐시 일관성** 메시지 중계 | Ring Bus 또는 2D Mesh 토폴로지 |
| 공유 저장 계층 | 공유 LLC (L3 캐시) | 코어 간 데이터 공유 지원 및 메모리 접근 완충 | 대용량 분할 슬라이스 구조 |
| 메모리 제어 계층 | 통합 메모리 제어기 | 다중 메모리 채널 스케줄링 및 DRAM 접근 중재 | 온다이 고속 메모리 인터페이스 |

#### 한줄 요약
- 멀티코어는 코어별 사설 캐시 ➔ 온칩 인터커넥트 ➔ 공유 LLC ➔ 통합 메모리 제어기의 4단계 계층 구조로 집적된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스누핑(Snooping)**: 공유 버스를 통해 모든 캐시 컨트롤러가 브로드캐스트되는 메모리 트랜잭션을 감시하여 일관성을 유지하는 방식.
- **무효화(Invalidation)**: 한 코어가 데이터를 쓸 때 타 코어의 사설 캐시에 있는 동일 라인을 무효 상태로 바꾸는 일관성 동작.

</details>

```text
코어 A의 사설 캐시 공유 데이터 갱신 요청
                      │
                      ▼
1. 코어 A의 캐시 라인 상태 판정 (MESI 프로토콜)
   ┌──────────────────┴──────────────────┐
[ 독점/수정 상태 (M/E) ]               [ 공유 상태 (S) ]
   │                                     │
   ├─ 즉시 로컬 캐시 쓰기 완료           ▼
   │                             2. 온칩 인터커넥트로 무효화(Invalidate) 브로드캐스트
   │                                     │
   │                                     ▼
   │                             3. 타 코어들의 동일 주소 캐시 라인 무효화 완료
   │                                     │
   │                                     ▼
   │                             4. 코어 A가 수정(M) 상태로 승격 후 쓰기 완료
   └──────────────────┬──────────────────┘
                      │
                      ▼
5. 타 코어의 해당 주소 읽기 요청 시 최신 데이터 스누핑 제공
```

분기 결과: **독점 상태**에서는 코어 내부에서 즉시 쓰기가 끝나나, **공유 상태**에서는 인터커넥트 무효화 트래픽이 발생하여 통신 지연이 수반됨

#### 한줄 요약
- 멀티코어에서 데이터 갱신 시 캐시 일관성 프로토콜이 인터커넥트를 통해 타 코어의 사본을 무효화한 후 안전하게 쓰기를 완료한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대칭 다중 처리(SMP)**: 동일한 성능의 코어들이 단일 메모리를 균등하게 공유하는 구조.
- **이종 멀티코어(Heterogeneous)**: 고성능 빅 코어와 저전력 리틀 코어를 결합한 구조(ARM big.LITTLE).
- **동시 멀티스레딩(SMT)**: 단일 코어 내부에서 하드웨어 스레드 문맥을 복수 유지하는 기술.

</details>

| 멀티코어 유형 | 대칭 멀티코어 (SMP) | 이종 멀티코어 (big.LITTLE / DynamIQ) | 동시 멀티스레딩 (SMT) |
|:---|:---|:---|:---|
| 아키텍처 구조 | **동일 마이크로아키텍처** 구성 | **빅·리틀 코어** 혼합 구성 | **단일 코어 내 복수 문맥** 공유 |
| 주요 적용 분야 | 고성능 서버, 클라우드 가상화 노드 | 스마트폰, 모바일 기기, 최신 PC 프로세서 | 서버 및 고성능 데스크톱 프로세서 |
| 핵심 장점 | 일관된 성능 및 단순한 OS 스케줄링 | 워크로드 부하에 따른 전력 소모 극소화 | 최소 추가 면적으로 20~30% 처리량 향상 |
| 설계 한계 | 저부하 시 전력 낭비, 고부하 시 발열 집중 | 코어 간 태스크 마이그레이션 오버헤드 | 스레드 간 실행 유닛 및 캐시 간섭 |

#### 한줄 요약
- 일관된 연산 성능에는 대칭 멀티코어, 배터리 기반 에너지 효율에는 이종 멀티코어, 단일 코어 자원 극대화에는 SMT가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 독립된 변수를 갱신하지만, 동일한 물리 캐시 라인(64B)에 속해 있어 불필요한 무효화가 반복되는 성능 저하 현상.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립 변수 사이에 더미 바이트를 채워 서로 다른 캐시 라인에 위치시키는 기법.
- **비균일 메모리 접근(NUMA)**: 소켓별로 로컬 메모리를 분할 배치하여 메모리 접근 지연이 불균일한 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수 갱신인데 캐시 라인이 겹쳐 **거짓 공유** 발생 | **캐시 라인 패딩(64B 정렬)** 적용 | 불필요한 인터커넥트 무효화 트래픽 제거 |
| 코어 수 증가에 따른 공유 버스 대역폭 포화 | **2D Mesh 인터커넥트** 및 **디렉터리 일관성** 채택 | 대규모 코어 확장 시에도 선형적 통신 대역폭 보장 |
| 다중 소켓 환경에서 원격 노드 메모리 접근 지연 급증 | **NUMA 인식 메모리 할당** 및 **스레드 바인딩** | 원격 메모리 참조 감소 및 로컬 DRAM 대역폭 극대화 |

#### 한줄 요약
- 멀티코어 실무에서는 거짓 공유를 패딩으로 방어하고, 코어 확장에 맞춘 Mesh 인터커넥트와 NUMA 인식 배치를 통해 병목을 통제한다.

## Ⅶ. 결론

- 워크로드 특성에 따른 **멀티코어 토폴로지** 선정과 **캐시 일관성** 최적화

#### 한줄 요약
- 멀티코어는 현대 컴퓨팅의 기본 구조이며, 캐시 일관성과 인터커넥트, NUMA 메모리 배치의 최적화가 시스템 확장성을 결정한다.
