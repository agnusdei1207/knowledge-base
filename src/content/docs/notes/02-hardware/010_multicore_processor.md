## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티코어 프로세서(Multicore Processor)**: 하나의 칩에 둘 이상의 독립 실행 코어를 집적해 스레드 수준 병렬성을 높이는 프로세서.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 독립 소프트웨어 스레드를 여러 코어에서 동시에 실행할 수 있는 병렬성.
- **전력 장벽(Power Wall)**: 단일 코어의 클록 주파수·전압 증가가 전력 소모와 발열 한계로 더 이상 성능 이득을 내지 못하는 현상.

</details>

- 정의/개념: 단일 실리콘 다이에 둘 이상의 독립 연산 코어를 집적하여 **스레드 수준 병렬성(TLP)**을 실현하는 프로세서 구조
- 배경/필요성: 단일 코어의 클록 주파수 증설 한계인 **전력 장벽(Power Wall)** 및 발열 포화 직면

#### 한줄 요약
- 멀티코어는 한 코어의 속도를 끝없이 높이는 대신, 여러 코어가 각자 다른 일을 맡아 전체 작업량을 늘리는 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law)**: 프로그램의 직렬 실행 비율이 코어 수와 무관하게 전체 가속비 상한을 결정한다는 법칙.
- **캐시 일관성(Cache Coherence)**: 여러 코어의 사설 캐시가 같은 메모리 위치에 대해 항상 올바른 값을 보이게 하는 성질.
- **인터커넥트(Interconnect)**: 코어·캐시·메모리 제어기 사이에서 데이터와 일관성 메시지를 전달하는 온칩 연결망.

</details>

- 코어 수 확장으로 **스레드 처리량 증대** 및 직렬 구간 암달의 법칙 제약
- 사설 캐시 사이의 동일 주소 갱신 시 **캐시 일관성** 프로토콜로 정확성 보장 필요
- 코어·LLC·메모리 간 **인터커넥트** 대역폭이 확장 가속비의 병목

#### 한줄 요약
- 코어를 늘리면 동시에 할 수 있는 일은 많아지지만, 순서대로 해야 하는 직렬 구간과 공유 데이터 일관성 비용이 가속비를 제한한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 캐시(Private Cache)**: 특정 코어에 전용으로 할당된 L1·L2 캐시로, 다른 코어와 공유하지 않음.
- **최종 단계 캐시(Last-Level Cache, LLC)**: 메인 메모리 앞의 마지막 온칩 캐시 계층; 여러 코어가 공유.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 프로세서 다이 내에 집적돼 메모리 채널 요청을 직접 관리하는 제어기.

</details>

```text
[멀티코어 칩]
├─ 코어 0 ── 사설 캐시(L1·L2)
├─ 코어 1 ── 사설 캐시(L1·L2)
│   ···
├─ 인터커넥트 (링·메시·크로스바)
├─ LLC (공유)
└─ IMC ── 메인 메모리
```

선의 의미: `──`는 데이터·일관성 메시지 전송 경로; 가지(`├─`)는 칩 내 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 코어 클러스터 | 스레드별 명령어 실행·레지스터 상태 보관 |
| 사설 캐시 | 코어 전용 고속 데이터·명령어 제공 |
| **인터커넥트** | **캐시 일관성** 메시지·공유 데이터 전달 |
| LLC | 코어 간 공유 데이터 완충·메모리 접근 감소 |
| IMC | 메모리 채널 요청 스케줄링·대역폭 관리 |

#### 한줄 요약
- 멀티코어 칩은 코어만 여러 개인 구조가 아니라, 코어 전용 캐시와 공유 LLC, 이를 잇는 인터커넥트와 메모리 제어기를 함께 갖춘 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **쓰기 소유권(Write Ownership)**: 캐시 라인을 수정하기 전에 특정 코어가 배타적으로 확보해야 하는 쓰기 권한.
- **무효화(Invalidation)**: 다른 코어의 사설 캐시에 있는 동일 주소의 오래된 사본을 사용 불가 상태로 만드는 동작.

</details>

```text
코어A: 공유 주소 쓰기 요청
          │
          ▼
사설 캐시 상태 확인
          │
     ┌────┴──────────────────┐
     │                       │
캐시 미스                캐시 히트·독점 상태
     │                       │
     ▼                       ▼
1. 인터커넥트 소유권 요청      → 쓰기 수행
     │
     ▼
2. 타 코어 캐시 라인 무효화 (인터커넥트 브로드캐스트)
     │
     ▼
3. 소유권 획득 및 쓰기 수행
```

**동작 원리**

1. **인터커넥트 소유권 요청**: 코어A가 쓰기 소유권 요청 브로드캐스트
2. **타 코어 캐시 라인 무효화**: 다른 코어의 동일 주소 라인을 무효화
3. **소유권 획득 및 쓰기 수행**: 소유권 확보 후 로컬 캐시 기록

#### 한줄 요약
- 한 코어가 공유 데이터를 쓰려면 다른 코어의 오래된 사본을 먼저 무효화해 모든 코어가 같은 최신 값을 보게 만든다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **대칭 다중 처리(Symmetric Multiprocessing, SMP)**: 동등한 코어에 OS가 스레드를 대칭적으로 배치하는 방식.
- **이종 멀티코어(Heterogeneous Multicore)**: 성능·전력 특성이 다른 코어를 한 칩에 함께 두는 구조(big.LITTLE 등).
- **동시 멀티스레딩(Simultaneous Multithreading, SMT)**: 한 물리 코어가 여러 하드웨어 스레드 상태를 유지해 실행 유닛을 공유하는 방식.

</details>

| 병렬 실행 구조 | SMP | 이종 멀티코어 | SMT |
|:---|:---|:---|:---|
| 적용 기준 | 균일한 작업 유형·단순 코어 확장 | 작업 유형별 성능·전력 요구 차이 | 단일 코어의 유휴 실행 자원 활용 |
| 핵심 특징 | 동등 코어의 균등 **TLP** 분산 | 고성능·고효율 코어 혼합 배치 | 한 코어 안의 다중 하드웨어 스레드 |
| 한계 | 공유 LLC·**인터커넥트** 경합 | 스케줄링·이종 코어 이전 비용 | 실행 유닛·사설 캐시 간섭 |

#### 한줄 요약
- 같은 코어를 많이 쓰면 SMP, 성격이 다른 코어를 섞으면 이종 멀티코어, 한 코어의 빈 실행 유닛을 다른 스레드가 채우면 SMT다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 변수가 같은 캐시 라인에 배치돼 독립 갱신인데도 일관성 트래픽이 발생하는 현상.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립적으로 갱신하는 데이터를 서로 다른 캐시 라인에 배치해 거짓 공유를 방지하는 기법.
- **비균일 메모리 접근(Non-Uniform Memory Access, NUMA)**: 메모리 위치에 따라 접근 지연과 대역폭이 달라지는 다소켓 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 갱신인데 캐시 라인 공유로 **거짓 공유** 발생 | **캐시 라인 패딩**·데이터 구조 재배치 | 불필요한 일관성 트래픽 감소 |
| 코어별 작업량 차이로 유휴 코어 발생 | 작업 훔치기·동적 부하 분산 적용 | 병렬 구간 코어 활용률 향상 |
| **NUMA** 원격 메모리 접근 지연 증가 | 스레드·메모리의 NUMA 인지 배치 | 원격 지연·대역폭 경합 완화 |
| 이종 코어에 작업 성격 불일치 | 성능·전력 힌트 기반 코어 배치 | 작업별 에너지 효율 향상 |

#### 한줄 요약
- 멀티코어 성능은 코어 수보다 데이터를 어디에 놓고, 작업을 어느 코어에 보내며, 공유 트래픽을 얼마나 줄이느냐에서 크게 달라진다.

## Ⅶ. 결론

- 병렬 워크로드는 **코어 수 확장**, 직렬 구간 우세 시 **암달의 법칙 상한 완화** 선행

#### 한줄 요약
- 멀티코어는 코어 수 경쟁이 아니라, 프로그램의 병렬 비율과 공유 데이터 비용이 추가 코어의 이득보다 작은지 확인하는 설계 선택이다.
