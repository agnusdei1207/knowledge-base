## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티코어 프로세서(Multicore Processor)**: 단일 반도체 칩 내부에 2개 이상의 독립된 CPU 코어를 집적하여 다중 스레드를 동시 처리하는 구조.
- **전력 한계(Power Wall)**: 클록 주파수와 전압 증가에 따른 전력 소모 및 발열이 반도체 패키징 한계를 초과하는 현상.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 독립된 소프트웨어 스레드들을 물리적으로 서로 다른 코어에서 동시 실행하는 기법.

</details>

- 정의/개념: 단일 반도체 다이에 2개 이상의 독립된 프로세서 코어를 집적하여 다중 소프트웨어 스레드를 동시에 병렬 처리하는 아키텍처
- 배경/필요성: 단일 코어의 클록 고속화가 직면한 **전력 한계(Power Wall) 및 발열 한계(Thermal Wall)를 극복하고 처리량(Throughput) 극대화**

#### 한줄 요약

- 단일 코어의 전력·발열 한계를 넘어 **스레드 수준 병렬성(TLP)**으로 처리량 극대화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암달의 법칙(Amdahl's Law)**: 병렬화가 불가능한 직렬 코드 구간 비율에 의해 코어를 무한히 늘려도 달성 가능한 최대 성능 향상비가 제한된다는 법칙.
- **가속비(Speedup)**: 단일 코어 실행 시간 대비 멀티코어 병렬 실행 시간의 단축 비율.

</details>

- 단일 스레드 지연시간 단축보다 다중 스레드 기반의 전체 **시스템 처리량(Throughput)** 확장
- 소프트웨어의 **스레드 수준 병렬성** 설계 수준에 비례하여 성능 향상 효과 발휘
- 코어 수 증가 시 **암달의 법칙(직렬 구간)**과 코어 간 **동기화/일관성 오버헤드**가 전체 가속비 제한

#### 한줄 요약

- 스레드 병렬성을 확장하나 **암달의 법칙(직렬 구간)과 동기화 오버헤드**가 가속비 제한

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사설 캐시(Private L1/L2)**: 각 코어 내부에 위치하여 독립적이고 빠른 데이터 접근을 제공하는 캐시.
- **공유 최종 캐시(Shared LLC / L3)**: 모든 코어가 인터커넥트를 통해 공유하며 메모리 접근을 완충하는 대용량 캐시.
- **일관성 인터커넥트(Coherence Interconnect)**: 사설 캐시 간 상태를 동기화하고 스누핑/디렉터리 패킷을 중계하는 버스 또는 크로스바 네트워크.

</details>

```text
[ 멀티코어 프로세서 아키텍처 ]
┌─────────────────────────┬─────────────────────────┐
│       Core 0            │       Core 1            │
│  [ L1 I/D ] [ L2 Cache ] │  [ L1 I/D ] [ L2 Cache ] │
└────────────┬────────────┴────────────┬────────────┘
             │                         │
═════════════╪═════════════════════════╪═════════════ (일관성 인터커넥트)
             │                         │
┌────────────┴─────────────────────────┴────────────┐
│         Shared Last-Level Cache (L3 Cache)        │
├───────────────────────────────────────────────────┤
│            통합 메모리 컨트롤러 (IMC)             │
└─────────────────────────┬─────────────────────────┘
                          ▼
                  DDR / HBM 메인 메모리
```

선의 의미: 코어별 사설 캐시, 일관성 인터커넥트, 공유 LLC 및 메모리 컨트롤러로 이어지는 멀티코어 계층 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 코어 클러스터 | 스레드별 독립 연산 명령 실행 수행 |
| 사설 캐시 (L1/L2) | 코어별 저지연 명령어와 데이터 제공 |
| 일관성 인터커넥트 | 캐시 일관성 프로토콜 패킷 전달 및 중재 |
| 최종 단계 캐시 (LLC) | 코어 간 공유 데이터 및 메모리 요청 완충 보관 |
| 메모리 제어기 (IMC) | 다중 코어의 주기억장치 채널 접근 중재 |

#### 한줄 요약

- **코어 클러스터·사설 L1/L2 캐시·일관성 인터커넥트·공유 LLC** 계층 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(MESI/MOESI)**: Modified, Exclusive, Shared, Invalid 상태를 전이하며 멀티코어 간 데이터 일치성을 보장하는 통신 규약.

</details>

```text
[ OS 스케줄러의 스레드 코어 배정 ]
                 │
                 ▼
[ 코어 사설 캐시 조회 (Read/Write) ]
                 │
                 ▼
[ 일관성 인터커넥트를 통한 쓰기 소유권 요청 ]
                 │
                 ▼
[ 타 코어 사설 캐시의 사본 무효화 (Invalidate) 신호 브로드캐스트 ]
                 │
                 ▼
[ 캐시 라인 데이터 갱신 및 Modified 상태 전이 ]
```

**동작 원리**

1. **스레드 할당**: OS 스케줄러가 코어 부하 및 캐시 친화도(Affinity)를 고려하여 작업 스레드 배치
2. **사설 캐시 조회**: 코어가 L1/L2 캐시에서 대상 데이터를 검색
3. **소유권 요청**: 쓰기 연산 시 인터커넥트로 메시지를 전송하여 캐시 라인의 독점 쓰기 권한 획득
4. **사본 무효화**: 다른 코어 사설 캐시에 존재하는 동일 캐시 라인을 Invalid 상태로 전이
5. **데이터 갱신**: 코어가 로컬 캐시를 갱신하고 Modified 상태로 유지하여 최신성 보장

#### 한줄 요약

- **쓰기 소유권 획득과 타 코어 사본 무효화(Invalidate)**로 데이터 일관성 보장

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SMP vs big.LITTLE vs SMT**:
  - SMP: 모든 코어가 동일한 동종 멀티코어
  - big.LITTLE: 고성능 빅코어와 고효율 리틀코어 결합
  - SMT: 단일 코어의 레지스터 세트만 복제하여 2개 스레드를 실행하는 하이퍼스레딩

</details>

| 아키텍처 분류 | 동종 멀티코어 (SMP) | 이종 멀티코어 (big.LITTLE) | 동시 멀티스레딩 (SMT) |
|:---|:---|:---|:---|
| 적용 기준 | 균일한 고성능이 요구되는 서버/HPC | 전력 제약과 부하 변동이 큰 모바일 AP | 단일 코어 유휴 자원 활용 및 데스크톱 CPU |
| 핵심 특징 | 모든 코어의 사양/IPC 동일, 스케줄링 단순 | 고성능 빅코어 + 고효율 리틀코어 결합 | 단일 코어 내 레지스터/파이프라인 공유(논리 코어) |
| 한계 및 위험 | 저부하 시 유휴 전력 소모 및 발열 증가 | 스레드 마이그레이션 오버헤드, 스케줄러 복잡도 | 코어 내부 실행 유닛/캐시 경합으로 인한 성능 간섭 |

#### 한줄 요약

- **동종(SMP)의 균일 성능, 이종(big.LITTLE)의 전력 효율, SMT의 자원 극대화**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 변수가 동일한 64바이트 캐시 라인에 위치하여 불필요하게 타 코어 캐시 무효화가 반복되는 현상.
- **캐시 라인 패딩(Padding)**: 변수 사이에 더미 바이트를 넣어 독립 캐시 라인으로 격리하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수 갱신으로 타 코어 무효화가 반복되는 **거짓 공유** 병목 | 변수 선언 시 메모리 간격 **캐시 라인 패딩** 적용 | 물리적 캐시 라인 격리로 무의미한 일관성 패킷 통신 절감 |
| 특정 코어에만 연산이 집중되고 다수 코어는 유휴 상태 체류 | 코어 간 부하를 동적으로 분배하는 **작업 훔치기** 스케줄러 도입 | 물리 코어 활용 부하 평형 달성 및 병렬 지연 단축 |
| 코어 수 증가 시 통합 메모리 버스 대역폭 포화 및 지연 | 스레드와 메모리를 매핑하는 **비균일 메모리 접근 인지 배치** | 원격 메모리 접근 최소화 및 메모리 대역폭 경합 완화 |
| **이종 멀티코어** 환경에서 작업 특성과 맞지 않는 오배정 발생 | 부하 힌트 및 운영체제 기반의 이종 코어 인지 스케줄링 | 지연 민감 작업과 배경 작업의 최적 배치로 전력 대 성능 극대화 |

#### 한줄 요약

- **캐시 라인 패딩·작업 훔치기·NUMA 인지 배치**로 통신 및 메모리 병목 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **암달의 벽**: 직렬 구간 비율이 5%만 존재해도 코어를 무한히 늘렸을 때 최대 가속비가 20배로 수렴하는 이론적 한계.

</details>

- 암달의 법칙 기반 직렬 구간 최소화 및 **캐시 지역성 중심의 NUMA/이종 코어 인지 스케줄링 적용**

#### 한줄 요약

- **직렬 구간과 메모리 대역폭 한계**를 고려한 최적 코어 확장 설계
