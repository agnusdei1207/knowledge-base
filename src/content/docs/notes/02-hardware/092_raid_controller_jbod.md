## 미리 알고가기

- **RAID 컨트롤러·JBOD**: RAID 컨트롤러는 여러 디스크를 하나의 중복 논리 볼륨으로 제공하고, JBOD는 개별 디스크를 상위 소프트웨어에 그대로 노출한다
- **독립 디스크 중복 배열(Redundant Array of Independent Disks, RAID)**: 여러 디스크에 데이터를 분산·중복하여 성능과 가용성을 조절하는 저장장치 구성
- **단순 디스크 묶음(Just a Bunch of Disks, JBOD)**: 하드웨어 RAID를 구성하지 않고 개별 디스크를 상위 소프트웨어에 직접 제공하는 방식
- **입출력(Input/Output, I/O)**: 호스트와 저장장치 사이에서 명령과 데이터를 전달하는 경로
- **스트라이핑(Striping)**: 데이터를 여러 디스크에 나눠 기록
- **미러링(Mirroring)**: 같은 데이터를 여러 디스크에 복제
- **패리티(Parity)**: 누락 데이터를 재구성하는 계산값
- **패스스루(Pass-Through)**: 디스크 명령·상태를 상위 계층에 그대로 전달
- **라이트백(Write-Back)**: 캐시 기록 후 완료하고 디스크에 지연 반영
- **전원 보호 쓰기 캐시(Power-Protected Write Cache)**: 정전에도 미반영 쓰기 데이터를 보존
- **RAID 재구성(Rebuild)**: 생존 데이터·패리티로 교체 디스크 복원
- **재복제(Re-replication)**: 생존 사본을 다른 디스크·노드에 복제
- **소프트웨어 정의 스토리지(Software-Defined Storage, SDS)**: 범용 서버의 소프트웨어가 데이터 배치·복제·장애 복구 정책을 담당하는 스토리지 구조
- **독립 디스크 중복 배열 1단계(Redundant Array of Independent Disks Level 1, RAID 1, 레이드 원)**: 숫자 1은 RAID의 미러링 수준 번호를 나타내며, 같은 데이터를 둘 이상의 디스크에 복제해 본문의 부트 볼륨을 보호함
- **논리 볼륨(Logical Volume)**: 여러 물리 디스크의 용량을 묶어 호스트에 하나의 블록 장치로 제공하는 공간
- **RAID 메타데이터(RAID Metadata)**: RAID 레벨·구성원·배치·재구성 상태를 기록하는 제어 정보
- **장애 영역(Failure Domain)**: 한 구성요소 장애가 함께 중단시키거나 성능을 떨어뜨리는 시스템 범위
- **분산 객체 스토리지(Distributed Object Storage)**: 데이터를 객체 단위로 여러 노드에 배치·복제해 제공하는 저장 시스템
- **부트 볼륨(Boot Volume)**: 운영체제와 부팅 파일을 저장해 서버 시작에 사용하는 논리 저장장치

## Ⅰ. 개요

- 정의/개념: 디스크를 논리 볼륨으로 묶거나 개별 장치로 노출하는 구성
- 기존 한계: 하드웨어와 소프트웨어 계층에서 복제·복구 기능을 중복 적용하면 용량·성능 비용이 증가하고 장애 처리 책임이 불명확해질 수 있다.

### 쉽게 이해하기 (학습용)

- 여러 디스크를 하드웨어 RAID 컨트롤러가 관리할지 상위 스토리지 소프트웨어가 개별 관리할지 결정한다.

## Ⅱ. 특징

- 보호 캐시는 라이트백 응답 지연을 줄인다.
- 단일 컨트롤러 장애는 배열 전체를 중단시킨다.
- JBOD 상태 노출이 SDS의 배치·격리 결정을 돕는다.

### 쉽게 이해하기 (학습용)

- RAID 컨트롤러는 쓰기 캐시로 지연을 줄일 수 있지만 단일 장애점이 될 수 있고, JBOD는 상위 소프트웨어가 디스크별 상태와 복구를 직접 관리한다.

## Ⅲ. 아키텍처 및 구성요소

### 도표안 A. RAID 컨트롤러·JBOD 저장 경로 정적 구조

```mermaid
flowchart TB
    H[호스트·파일시스템]
    subgraph S[저장 경로]
        subgraph R[RAID 컨트롤러 경로]
            C[전원 보호 쓰기 캐시]
            E[RAID 엔진·메타데이터]
            C -->|보호 쓰기| E
        end
        subgraph J[JBOD·SDS 경로]
            A[상위 스토리지 소프트웨어]
            P[패스스루 컨트롤러]
            A -->|개별 장치 I/O| P
        end
        D[물리 디스크]
        E -->|RAID 레벨 배치| D
        P <-->|명령·상태| D
    end
    H -->|논리 볼륨 I/O| C
    H -->|분산 데이터 I/O| A
```

| 설계 요소 | 입력·상태 | 역할 |
|:---|:---|:---|
| 전원 보호 쓰기 캐시 | 미반영 쓰기·전원 상태 | 안전한 라이트백 완료 제공 |
| RAID 엔진·메타데이터 | 논리 주소·레벨·구성원 상태 | 중복·패리티·재구성 관리 |
| 상위 스토리지 소프트웨어 | 개별 장치·장애 영역 | JBOD 배치·복제·복구 정책 적용 |
| 패스스루 컨트롤러 | 디스크 명령·상태 | 장치를 상위 계층에 투명하게 노출 |
| 물리 디스크 | 블록·건강 상태 | RAID 구성원 또는 JBOD 용량 제공 |

> 요약: RAID는 논리 볼륨, JBOD는 개별 디스크를 노출

### 쉽게 이해하기 (학습용)

- RAID 경로는 서랍을 한 문 뒤에 숨기고 JBOD 경로는 각 서랍의 이름과 상태를 상위 관리자에게 알린다.

### 도표안 B. 전원 보호 라이트백 RAID 쓰기 시퀀스

```mermaid
sequenceDiagram
    participant H as 호스트
    participant C as 전원 보호 쓰기 캐시
    participant E as RAID 엔진·메타데이터
    participant D1 as 데이터 디스크
    participant D2 as 미러·패리티 디스크
    participant M as 상태 감시기

    H->>C: ① 논리 블록 쓰기 요청
    C->>M: ② 캐시 전원 보호 상태 확인
    M-->>C: ③ 라이트백 허용 반환
    C-->>H: ④ 보호 캐시 기록 후 완료
    C->>E: ⑤ 논리 주소·데이터 배치 요청
    E->>D1: ⑥ 데이터 스트립 쓰기
    E->>D2: ⑦ 미러 사본·패리티 쓰기
    D1-->>E: ⑧ 데이터 쓰기 완료
    D2-->>E: ⑨ 중복 쓰기 완료
    E->>C: ⑩ RAID 메타데이터·디스크 반영 완료
    C->>M: ⑪ 캐시 항목 해제·건강 상태 기록
```

#### 동작 원리

1. 호스트가 RAID 논리 볼륨의 블록 주소에 쓰기를 요청한다.
2. 캐시가 배터리·플래시 백업과 전원 보호 회로의 정상 상태를 확인한다.
3. 보호가 유효할 때만 라이트백 정책을 허용하며 실패 시 라이트스루로 전환한다.
4. 정전 뒤 복구 가능한 캐시에 데이터가 기록되면 호스트에 먼저 완료할 수 있다.
5. RAID 엔진이 논리 주소를 RAID 레벨의 스트립·미러·패리티 위치로 변환한다.
6. 선택한 구성원 디스크에 실제 데이터 스트립을 기록한다.
7. RAID 1은 사본, 패리티 RAID는 계산한 패리티와 관련 데이터를 중복 디스크에 기록한다.
8. 데이터 디스크가 지속 쓰기 완료를 반환한다.
9. 중복 디스크도 쓰기 완료를 반환한다.
10. 필요한 데이터·중복·RAID 메타데이터가 모두 반영되면 캐시에 완료를 알린다.
11. 캐시 항목을 해제하고 디스크 오류·지연 상태를 감시기에 기록한다.

### 쉽게 이해하기 (학습용)

- 정전 보호 캐시가 쓰기를 먼저 안전하게 받아 주고, 뒤에서 RAID 규칙에 따라 여러 디스크에 모두 반영한다.

## Ⅳ. 종류 및 비교

| 판단 기준 | RAID 컨트롤러 | JBOD 패스스루 |
|:---|:---|:---|
| 핵심 특징 | 논리 볼륨의 중복·재구성 관리 | 개별 디스크를 상위 SDS에 노출 |
| 적용 기준 | 단일 서버 내부 볼륨 보호 | 분산 스토리지 사본 관리 |
| 주요 위험 | 컨트롤러 장애·재구성 부하 | 상위 복제 정책 오류·상태 관리 |

> 요약: 단일 서버 보호는 RAID, 분산 복제는 JBOD·SDS

## Ⅴ. 실무 고려사항 및 대응 방안

| 운영 위험 | 대응 | 기대 효과 |
|:---|:---|:---|
| 보호되지 않은 라이트백 캐시의 정전 손실 | 캐시 전원 보호 상태 감시와 실패 시 라이트스루 전환 | 승인된 쓰기 보존 |
| 재구성·재복제가 정상 I/O를 압박 | 우선순위·속도 제한과 취약 시간·완료 시간 감시 | 서비스 영향·노출 시간 균형 |
| 하드웨어 RAID와 SDS 중복 보호 | 보호·복구 책임을 한 계층에 명시 | 용량 낭비·장애 판단 혼선 방지 |
| 컨트롤러·메타데이터 종속으로 교체 복구 실패 | 호환 예비품·구성 백업과 실제 복구 훈련 | 배열 복구 가능성 확보 |

### 쉽게 이해하기 (학습용)

- RAID는 남은 조각으로 새 디스크를 복원하고 JBOD 위 소프트웨어는 다른 노드의 사본을 다시 복제한다.

### 적용 사례

- 서버 부트 볼륨은 RAID 1과 전원 보호 쓰기 캐시를 적용하고, 분산 객체 스토리지는 JBOD 상태를 상위 SDS에 노출해 노드 간 재복제를 수행한다.

### 쉽게 이해하기 (학습용)

- 부팅 디스크는 같은 내용을 두 장에 쓰고 정전 때도 캐시의 미반영 쓰기를 보존한다.

## Ⅵ. 결론

- 저장 보호 책임을 명확히 하기 위해 **중복 계층·캐시 전원 보호·컨트롤러 장애·재구성 부하·디스크 상태 가시성**을 검토하고, 단일 서버 볼륨은 RAID, 분산 복제는 JBOD·SDS를 선택한다.

### 쉽게 이해하기 (학습용)

- 한 서버가 고장을 복구하면 RAID이고 여러 서버의 소프트웨어가 사본을 복구하면 JBOD 경로이다.
