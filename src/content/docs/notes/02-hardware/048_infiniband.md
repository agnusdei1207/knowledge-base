## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인피니밴드(InfiniBand)**: 고성능 컴퓨팅(HPC) 및 데이터센터에서 서버와 스토리지 간 초고속·초저지연 통신을 제공하는 스위치형 패브릭 네트워킹 표준.
- **원격 직접 메모리 접근(Remote Direct Memory Access, RDMA)**: 등록된 버퍼 사이의 데이터 경로에서 커널 복사를 우회해 HCA가 원격 메모리에 접근하는 기술.

</details>

- 정의/개념: **원격 직접 메모리 접근(Remote Direct Memory Access, RDMA)**과 전용 스위치 패브릭을 결합해 노드 간 지연을 최소화한 **인피니밴드(InfiniBand)**
- 배경/필요성: 잦은 소규모 메시지와 대용량 집단 통신에서는 전송 자체보다 커널 처리와 메모리 복사가 지연을 지배

#### 한줄 요약
- 이 기술이 줄이는 것은 전선 위의 시간이 아니라 소프트웨어 계층에서 소모되던 시간이며, 그래서 대역폭보다 지연에서 격차가 크게 벌어진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커널 우회(Kernel Bypass)**: 사용자 공간 응용 프로그램이 OS 커널 시스템 콜 없이 HCA 하드웨어와 직접 통신하여 지연을 단축하는 기법.
- **제로 카피(Zero-Copy)**: 중간 소켓 버퍼 복사 과정을 완전히 없애고 사용자 메모리 버퍼에서 네트워크 인터페이스로 직접 전송하는 기술.

</details>

- **커널 우회(Kernel Bypass)**와 **제로 카피(Zero-Copy)**로 데이터 경로에서 CPU와 복사를 제거
- 하드웨어 크레딧 흐름 제어로 수신 버퍼가 넘쳐 패킷을 버리는 상황 자체를 차단
- 서브넷 관리자가 토폴로지를 파악해 경로를 중앙에서 설정하고 부하를 분산

#### 한줄 요약
- 패킷을 버리지 않는다는 전제가 성능의 근거이므로, 무손실 가정이 깨지는 순간 재전송 비용이 이더넷보다 오히려 커진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **HCA(Host Channel Adapter)**: 인피니밴드 패브릭과 서버의 호스트 버스(PCIe)를 연결하는 전용 네트워크 어댑터 카드.
- **큐 페어(Queue Pair, QP)**: 송신 큐(SQ)와 수신 큐(RQ)로 구성된 RDMA 비동기 통신 엔드포인트.
- **완료 큐(Completion Queue, CQ)**: 전송 작업의 완료 통지(Work Completion)를 수집하고 애플리케이션에 전달하는 큐.

</details>

```text
[InfiniBand 패브릭]
├─ 노드
│  ├─ 사용자 공간 애플리케이션 메모리
│  └─ HCA (호스트 채널 어댑터)
│     ├─ 큐 페어 (송신 큐·수신 큐)
│     └─ 완료 큐
├─ InfiniBand 스위치 (컷스루 전달)
└─ 서브넷 관리자 (토폴로지 탐색·LID 할당·라우팅 구성)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 애플리케이션 메모리에서 HCA로 넘어가는 지점이 커널을 건너뛰는 유일한 경계

| 구성요소 | 책임 |
|:---|:---|
| **HCA(Host Channel Adapter)** | RDMA 패킷화·주소 변환·하드웨어 전송 엔진 구동 |
| **큐 페어(Queue Pair, QP)** | 송수신 큐로 비동기 작업 요청 처리 |
| **완료 큐(Completion Queue, CQ)** | 전송·수신 작업의 성공·실패 통지 수집 |
| 서브넷 관리자 | 토폴로지 탐색·주소 할당·라우팅 테이블 구성 |
| 인피니밴드 스위치 | 서브넷 관리자가 설정한 경로에 따라 패킷을 컷스루 전달 |

#### 한줄 요약
- 경로 결정이 스위치마다 자율적으로 이뤄지지 않고 중앙 관리자에 모여 있어 최적 경로를 얻는 대신, 그 관리자가 패브릭 전체의 단일 의존 지점이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **메모리 등록(Memory Registration)**: RDMA 전송 대상 메모리 버퍼를 HCA에 등록하여 가상-물리 주소를 고정(Pinning)하고 L_Key/R_Key를 발급받는 작업.

</details>

```text
RDMA 통신 초기화
        │
   대상 버퍼가 등록돼 있는가?
   ┌────┴─────┐
  예           아니오
   │             │
   │        메모리 등록: 페이지 고정 후 보호 키 발급·교환
   └────┬────────┘
        │
   애플리케이션이 송신 큐에 작업 요청 등록
        │
   HCA가 DMA로 읽어 패킷화 후 패브릭 전송
        │
   원격 HCA가 키와 범위를 검증
   ┌────┴─────┐
검증 실패      통과
   │             │
오류 완료 통지  등록된 버퍼에 직접 기록
   └────┬────────┘
        │
   완료 큐 폴링으로 결과 확인
```

분기 결과: 등록과 키 검증이 전송 경로 밖에서 한 번만 이뤄지므로 이후 전송에는 소프트웨어 개입이 전혀 없고, 그 대신 등록된 페이지는 스왑 대상에서 빠져 메모리 유연성을 잃음

#### 한줄 요약
- **메모리 등록(Memory Registration)** 비용이 전송 횟수와 무관한 고정 비용이므로, 짧은 연결을 반복하는 사용 방식에서는 RDMA의 이점이 사라진다.

## Ⅴ. 종류 및 비교

| 고성능 네트워킹 기술 | InfiniBand | RoCE v2 | iWARP | 전통 TCP/IP (Ethernet) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초대규모 AI 분산 학습 및 슈퍼컴퓨팅 | 기존 이더넷 인프라 기반 RDMA 구축 | 표준 TCP/IP 라우팅 환경 RDMA | 일반 엔터프라이즈 웹 및 파일 전송 |
| 핵심 특징 | 전용 HCA·스위치 패브릭 및 무손실 흐름 제어 | 표준 이더넷(PFC/ECN) 위에서 RDMA 지원 | 복잡한 TCP 스택 하드웨어 오프로딩 | 높은 범용성 및 광범위한 인터넷 호환성 |
| 한계 | 고가의 전용 장비 및 이더넷과의 상호운용 제약 | 패킷 유실 시 성능 급락 및 스위치 튜닝 난이도 | 하드웨어 칩셋 고비용 및 낮은 시장 점유율 | 극심한 커널 CPU 부하 및 긴 지연시간 |

#### 한줄 요약
- 네 기술의 실제 갈림길은 무손실을 하드웨어가 보장하느냐 운영자가 튜닝으로 만들어 내느냐이며, 후자는 성능이 아니라 운영 역량을 요구한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **GPUDirect RDMA**: CPU 메모리를 거치지 않고 네트워크 HCA가 GPU HBM 메모리에 직접 읽기·쓰기를 수행하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 확장 시 서브넷 관리자에 부하 집중 | 서브넷 분할과 관리자 이중화 구성 | 토폴로지 변경 수렴 시간 단축·가용성 확보 |
| 특정 스위치 포트에 트래픽 집중 | 적응형 라우팅과 혼잡 제어 정책 적용 | 경로 집중과 꼬리 지연 완화 |
| CPU 메모리를 경유하는 GPU 통신 복사 | **GPUDirect RDMA**로 HCA와 GPU 메모리 직접 전송 | 호스트 버퍼 복사와 CPU 개입 감소 |
| 데이터센터 간 장거리 연동 제약 | 이더넷 게이트웨이 또는 장거리 라우터 연동 | 원격지 복제와 하이브리드 확장 확보 |

#### 한줄 요약
- **GPUDirect RDMA**가 보여 주듯 최적화의 방향은 계속 CPU를 경로에서 밀어내는 쪽이며, 남은 병목이 있다면 대개 아직 우회하지 못한 소프트웨어 계층이다.

## Ⅶ. 결론

- 지연 예측성과 무손실 보장이 중요하고 전용 패브릭을 운영할 역량이 있으면 **인피니밴드(InfiniBand)**, 기존 이더넷 통합이 우선이면 RoCE 계열을 선택하되 혼잡 제어 튜닝 부담을 함께 계산

#### 한줄 요약
- 이 선택에서 자주 빠지는 항목은 장비 가격이 아니라 전용 패브릭을 계속 운영할 인력이며, 그 역량이 없으면 무손실 전제가 현장에서 먼저 무너진다.
