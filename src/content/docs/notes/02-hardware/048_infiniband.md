## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인피니밴드(InfiniBand)**: 고성능 컴퓨팅(HPC) 및 데이터센터에서 서버와 스토리지 간 초고속·초저지연 통신을 제공하는 스위치형 패브릭 네트워킹 표준.
- **원격 직접 메모리 접근(Remote Direct Memory Access, RDMA)**: 운영체제 커널의 개입과 메모리 복사 없이 네트워크 어댑터가 원격 호스트 메모리에 직접 읽기·쓰기를 수행하는 기술.

</details>

- 정의/개념: **RDMA** 및 전용 스위치 패브릭을 결합해 노드 간 통신 지연을 극소화한 **인피니밴드** 패브릭
- 배경/필요성: 기존 TCP/IP 스택의 커널 인터럽트 및 다중 버퍼 복사로는 **대규모 클러스터 통신 병목 해소 불가**

#### 한줄 요약
- 인피니밴드는 커널 우회와 제로 카피를 하드웨어 레벨에서 지원하여 마이크로초 단위의 초저지연과 무손실 대역폭을 제공하는 네트워크 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커널 우회(Kernel Bypass)**: 사용자 공간 응용 프로그램이 OS 커널 시스템 콜 없이 HCA 하드웨어와 직접 통신하여 지연을 단축하는 기법.
- **제로 카피(Zero-Copy)**: 중간 소켓 버퍼 복사 과정을 완전히 없애고 사용자 메모리 버퍼에서 네트워크 인터페이스로 직접 전송하는 기술.

</details>

- **커널 우회** 및 **제로 카피** 기반 데이터 경로에서 CPU 부하 및 메모리 복사 배제
- 링크 레벨 크레딧 기반 흐름 제어로 패킷 유실을 원천 방지하는 **무손실 패브릭** 구현
- 중앙화된 서브넷 관리자 기반 결정론적 라우팅 및 동적 부하 분산 지원

#### 한줄 요약
- 하드웨어 기반 크레딧 흐름 제어로 패킷 손실을 원천 차단하고 CPU 개입 없이 메모리 간 직접 데이터 이동을 실현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **HCA(Host Channel Adapter)**: 인피니밴드 패브릭과 서버의 호스트 버스(PCIe)를 연결하여 RDMA 프로토콜 엔진을 하드웨어로 처리하는 전용 어댑터.
- **큐 페어(Queue Pair, QP)**: RDMA 비동기 통신을 위해 송신 큐(Send Queue)와 수신 큐(Receive Queue)로 구성된 엔드포인트 작업 큐 쌍.
- **완료 큐(Completion Queue, CQ)**: HCA가 처리 완료한 송수신 작업의 결과(Work Completion)를 수집하여 응용 프로그램에 통지하는 큐.

</details>

```text
[InfiniBand 패브릭]
|-- 노드 엔드포인트
|   |-- 사용자 공간 메모리 버퍼
|   `-- HCA (호스트 채널 어댑터)
|       |-- 큐 페어 (송신 큐·수신 큐)
|       `-- 완료 큐
|-- InfiniBand 스위치 패브릭 (컷스루 스위칭)
`-- 서브넷 관리자 (토폴로지 탐색·LID 할당·라우팅 구성)
```

선의 의미: 계층 및 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| **HCA** | RDMA 패킷화, 가상 주소 변환 및 하드웨어 전송 엔진 구동 |
| **큐 페어(QP)** | 송신 큐(SQ)와 수신 큐(RQ)를 통한 비동기 전송 요청 처리 |
| **완료 큐(CQ)** | 전송 및 수신 작업의 성공·실패 완료 통지 수집 |
| 서브넷 관리자 | 네트워크 토폴로지 탐색, LID 할당 및 라우팅 테이블 구성 |
| 인피니밴드 스위치 | 서브넷 관리자가 설정한 경로에 따라 패킷을 컷스루 전달 |

#### 한줄 요약
- HCA 내부의 큐 페어와 완료 큐를 통해 비동기 I/O를 처리하고 중앙 서브넷 관리자가 패브릭 전체의 경로를 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **메모리 등록(Memory Registration)**: RDMA 송수신에 사용할 가상 메모리 영역을 OS 페이지에 고정(Pinning)하고 가상-물리 주소 매핑 및 보호 키(L_Key/R_Key)를 발급받는 작업.

</details>

```text
RDMA 통신 초기화
        │
   대상 버퍼가 등록돼 있는가?
   ┌────┴─────┐
  예           아니오
   │             │
   │        메모리 등록: 페이지 고정 후 보호 키 발급·교환
   └────┬────────┘
        │
   애플리케이션이 송신 큐에 작업 요청 등록
        │
   HCA가 DMA로 읽어 패킷화 후 패브릭 전송
        │
   원격 HCA가 키와 범위를 검증
   ┌────┴─────┐
검증 실패      통과
   │             │
오류 완료 통지  등록된 버퍼에 직접 기록
   └────┬────────┘
        │
   완료 큐 폴링으로 결과 확인
```

#### 한줄 요약
- 사전에 등록된 메모리 버퍼를 기반으로 HCA가 직접 DMA 전송을 수행하며, 원격지에서 키 검증 후 즉시 대상 메모리에 기록한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RoCE v2(RDMA over Converged Ethernet v2)**: 표준 이더넷 인프라 위에서 UDP/IP 캡슐화를 통해 RDMA를 구현하는 기술.
- **iWARP**: 표준 TCP/IP 프로토콜 스택 위에서 RDMA 통신을 제공하는 네트워킹 표준.

</details>

| 고성능 네트워킹 기술 | InfiniBand | RoCE v2 | iWARP | 전통 TCP/IP (Ethernet) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초대규모 AI 분산 학습 및 슈퍼컴퓨팅 | 기존 이더넷 인프라 기반 RDMA 구축 | 표준 TCP/IP 라우팅 환경 RDMA | 일반 엔터프라이즈 웹 및 파일 전송 |
| 핵심 특징 | 전용 HCA·스위치 패브릭 및 무손실 흐름 제어 | 표준 이더넷(PFC/ECN) 위에서 RDMA 지원 | 복잡한 TCP 스택 하드웨어 오프로딩 | 높은 범용성 및 광범위한 인터넷 호환성 |
| 한계 | 고가의 전용 장비 및 이더넷과의 상호운용 제약 | 패킷 유실 시 성능 급락 및 스위치 튜닝 난이도 | 하드웨어 칩셋 고비용 및 낮은 시장 점유율 | 극심한 커널 CPU 부하 및 긴 지연시간 |

#### 한줄 요약
- 초고성능 AI 클러스터 전용망에는 InfiniBand가 최적이며, 기존 이더넷 인프라를 재활용할 때는 RoCE v2가 대안으로 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **GPUDirect RDMA**: CPU 시스템 메모리를 거치지 않고 네트워크 HCA가 GPU VRAM(HBM) 메모리에 직접 P2P 전송을 수행하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 확장 시 서브넷 관리자 단일 장애점(SPOF) | 서브넷 분할 및 관리자 이중화(Active-Standby) 구성 | 토폴로지 수렴 시간 단축 및 패브릭 고가용성 확보 |
| 특정 스위치 포트에 트래픽 집중 및 정체 | 적응형 라우팅(Adaptive Routing) 및 ECN 혼잡 제어 | 트래픽 경로 분산 및 테일 레이턴시 안정화 |
| CPU 메모리를 경유하는 GPU 간 통신 병목 | **GPUDirect RDMA** 기반 HCA와 GPU VRAM 직접 전송 | 호스트 버퍼 복사 오버헤드 제거 및 통신 가속 |
| 데이터센터 간 장거리 패브릭 연동 한계 | InfiniBand-Ethernet 게이트웨이 및 라우터 연동 | 원격지 데이터 복제 및 하이브리드 확장성 확보 |

#### 한줄 요약
- 실무 AI 클러스터 구축 시 GPUDirect RDMA 연동과 서브넷 관리자 이중화 설계를 통해 무손실 고가용성 인프라를 완성한다.

## Ⅶ. 결론

- 초대규모 분산 딥러닝과 HPC는 **InfiniBand 패브릭**을 구축하고, 비용과 기존 이더넷 자원 활용이 우선되면 **RoCE v2** 기반으로 전환 설계

#### 한줄 요약
- 인피니밴드 채택의 핵심은 무손실 전송의 하드웨어 보장 여부와 대규모 패브릭 관리 역량 확보에 있다.
