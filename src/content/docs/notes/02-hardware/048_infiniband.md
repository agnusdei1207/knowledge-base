## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인피니밴드(InfiniBand)**: 고성능 컴퓨팅(HPC) 및 데이터센터에서 서버와 스토리지 간 초고속·초저지연 통신을 제공하는 스위치형 패브릭 네트워킹 표준.
- **원격 직접 메모리 접근(Remote Direct Memory Access, RDMA)**: 운영체제 커널의 개입 없이 네트워크 어댑터가 원격 노드의 메모리에 직접 데이터를 읽고 쓰는 기술.

</details>

- 정의/개념: 서버 및 스토리지 노드 간 대용량 데이터 전송을 위해 **RDMA(원격 직접 메모리 접근)**와 전용 스위치 패브릭을 제공하는 초저지연 네트워킹 기술
- 배경/필요성: HPC 및 대규모 AI 클러스터에서 전통적 TCP/IP 스택의 **CPU 오버헤드 및 패킷 지연** 병목 직면

#### 한줄 요약
- 커널을 거치지 않고 상대방 컴퓨터의 메모리에 직접 데이터를 쓰는 초고속 전용 네트워킹 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커널 우회(Kernel Bypass)**: 사용자 공간 응용 프로그램이 OS 커널 시스템 콜 없이 HCA 하드웨어와 직접 통신하여 지연을 단축하는 기법.
- **제로 카피(Zero-Copy)**: 중간 소켓 버퍼 복사 과정을 완전히 없애고 사용자 메모리 버퍼에서 네트워크 인터페이스로 직접 전송하는 기술.

</details>

- **커널 우회(Kernel Bypass)** 및 제로 카피 기반 마이크로초($\mu s$) 미만 초저지연
- 하드웨어 기반 **크레딧 흐름 제어(Credit-based Flow Control)**로 패킷 유실 원천 차단
- **서브넷 관리자(Subnet Manager)**를 통한 중앙집중식 경로 설정 및 동적 부하 분산

#### 한줄 요약
- 커널 우회와 제로 카피, 무손실 패브릭 흐름 제어로 CPU 낭비 없이 최고 속도의 클러스터 통신을 실현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **HCA(Host Channel Adapter)**: 인피니밴드 패브릭과 서버의 호스트 버스(PCIe)를 연결하는 전용 네트워크 어댑터 카드.
- **큐 페어(Queue Pair, QP)**: 송신 큐(SQ)와 수신 큐(RQ)로 구성된 RDMA 비동기 통신 엔드포인트.
- **완료 큐(Completion Queue, CQ)**: 전송 작업의 완료 통지(Work Completion)를 수집하고 애플리케이션에 전달하는 큐.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ InfiniBand 아키텍처 및 RDMA 계층                            │
│                                                             │
│  [ 송신 노드 ]                              [ 수신 노드 ]   │
│  ┌────────────────────────┐                 ┌─────────────┐ │
│  │ 사용자 공간 App (Memory)│                 │ App Memory  │ │
│  └───────────┬────────────┘                 └──────▲──────┘ │
│              │ (Kernel Bypass / Zero-Copy)         │         │
│  ┌───────────▼────────────┐                 ┌──────┴──────┐ │
│  │ HCA (QP / CQ Engine)   │                 │ HCA Engine  │ │
│  └───────────┬────────────┘                 └──────▲──────┘ │
│              │ (InfiniBand Link)                   │         │
│  ┌───────────▼─────────────────────────────────────┴──────┐ │
│  │ InfiniBand 스위치 패브릭 (Subnet Manager 기반 라우팅)   │ │
│  └────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 사용자 공간에서 HCA 하드웨어를 직접 제어하여 커널 경유 없이 스위치 패브릭을 통해 원격 노드 메모리로 직결

| 구성요소 | 책임 |
|:---|:---|
| 호스트 채널 어댑터 (HCA) | PCIe 버스와 직결되어 RDMA 패킷화, 주소 변환 및 하드웨어 전송 엔진 구동 |
| 큐 페어 (Queue Pair, QP) | 송신 큐(SQ)와 수신 큐(RQ)를 통해 비동기 작업 요청(Work Request) 처리 |
| 완료 큐 (Completion Queue) | RDMA 전송 및 수신 작업이 성공 또는 실패했음을 통지하는 큐 관리 |
| 서브넷 관리자 (SM) | 네트워크 토폴로지 탐색, 노드 LID(Local ID) 할당 및 최적 라우팅 테이블 구성 |
| 인피니밴드 스위치 | 비차단(Non-blocking) 컷스루 스위칭으로 수백 나노초 단위 패킷 중계 |

#### 한줄 요약
- HCA 어댑터, 큐 페어(QP), 완료 큐(CQ), 서브넷 관리자(SM), 고속 스위치가 하나의 패브릭을 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **메모리 등록(Memory Registration)**: RDMA 전송 대상 메모리 버퍼를 HCA에 등록하여 가상-물리 주소를 고정(Pinning)하고 L_Key/R_Key를 발급받는 작업.

</details>

```text
RDMA 통신 초기화 및 버퍼 준비
      │
      ▼
1. 메모리 등록: 가상 버퍼 물리 주소 고정(Pinning) 및 접근 키(R_Key) 교환
      │
      ▼
2. 작업 요청(WR): 애플리케이션이 송신 큐(SQ)에 RDMA Write 요청 포스팅
      │
      ▼
3. HCA DMA: 커널 개입 없이 로컬 메모리에서 직접 데이터를 읽어 패킷 전송
      │
      ▼
4. 원격 HCA: R_Key 유효성 검증 후 수신 노드 메모리에 Zero-Copy 직접 기록
      │
      ▼
5. CQ 통지: 완료 큐(CQ)에 이벤트 기록 및 작업 완료 폴링(Polling) 확인
```

**동작 원리**

1. **메모리 등록**: 송수신 버퍼를 페이징되지 않도록 고정하고 보호 키(R_Key)를 생성해 상호 교환
2. **비동기 요청 포스팅**: 애플리케이션이 HCA 큐 페어(QP)의 송신 큐에 작업 요청(WR) 등록
3. **하드웨어 전송**: HCA가 DMA로 로컬 메모리를 읽어 인피니밴드 패킷으로 캡슐화 후 패브릭 전송
4. **원격 메모리 직결 쓰기**: 원격 HCA가 키를 검증하고 대상 가상 주소의 물리 메모리에 즉시 복사
5. **완료 큐 회수**: 완료 큐(CQ)를 확인하여 전송 완료 상태를 폴링 방식으로 즉각 감지

#### 한줄 요약
- 메모리 등록 및 키 교환 → 작업 큐 등록 → HCA 전송 → 원격 메모리 직접 쓰기 → 완료 통지 순으로 실행된다.

## Ⅴ. 종류 및 비교

| 고성능 네트워킹 기술 | InfiniBand | RoCE v2 | iWARP | 전통 TCP/IP (Ethernet) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초대규모 AI 분산 학습 및 슈퍼컴퓨팅 | 기존 이더넷 인프라 기반 RDMA 구축 | 표준 TCP/IP 라우팅 환경 RDMA | 일반 엔터프라이즈 웹 및 파일 전송 |
| 핵심 특징 | 전용 HCA·스위치 패브릭 및 무손실 흐름 제어 | 표준 이더넷(PFC/ECN) 위에서 RDMA 지원 | 복잡한 TCP 스택 하드웨어 오프로딩 | 높은 범용성 및 광범위한 인터넷 호환성 |
| 한계 | 고가의 전용 장비 및 이더넷과의 상호운용 제약 | 패킷 유실 시 성능 급락 및 스위치 튜닝 난이도 | 하드웨어 칩셋 고비용 및 낮은 시장 점유율 | 극심한 커널 CPU 부하 및 긴 지연시간 |

#### 한줄 요약
- 최고 성능 AI 클러스터는 InfiniBand, 이더넷 기반 가성비 RDMA는 RoCE v2, 범용 통신은 TCP/IP를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **GPUDirect RDMA**: CPU 메모리를 거치지 않고 네트워크 HCA가 GPU HBM 메모리에 직접 읽기·쓰기를 수행하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 클러스터 스케일아웃 시 **서브넷 관리자(SM) 병목** | 다중 서브넷 분할 및 Master/Standby SM 이중화 구성 | 토폴로지 변경 시 빠른 수렴 및 가용성 보장 |
| 특정 스위치 포트 집중 시 **패브릭 혼잡(Congestion)** | 적응형 라우팅(Adaptive Routing) 및 ECN 기반 혼잡 알림 | 트래픽 분산 및 꼬리 지연시간(Tail Latency) 최소화 |
| CPU-GPU 간 데이터 전송으로 인한 **PCIe 병목** | **GPUDirect RDMA** 기술 적용으로 HCA-GPU 직결 | 중간 복사 오버헤드 제거 및 통신 처리율 극대화 |
| 장거리 데이터센터 간 InfiniBand 연동 한계 | InfiniBand-to-Ethernet 게이트웨이 또는 장거리 라우터 연동 | 원격지 데이터 복제 및 하이브리드 확장성 확보 |

#### 한줄 요약
- SM 이중화로 안정성을 확보하고, 적응형 라우팅으로 혼잡을 막으며, GPUDirect RDMA로 GPU를 직결한다.

## Ⅶ. 결론

- 초대규모 LLM 분산 학습 및 슈퍼컴퓨터 노드 간 초저지연 통신은 **InfiniBand**, 비용 효율적 엔터프라이즈는 **RoCE v2** 선택

#### 한줄 요약
- 커널 우회와 제로 카피 RDMA 기술, 무손실 패브릭 스위칭을 통해 데이터센터 클러스터의 전송 병목을 원천 해소해야 한다.
