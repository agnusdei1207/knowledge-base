## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AI 가속기(AI Accelerator)**: 신경망의 핵심 연산인 다차원 텐서 행렬 곱셈(GEMM)과 비선형 활성화를 CPU보다 압도적인 처리량과 전력 효율로 처리하는 도메인 특화 반도체.
- **워크로드 특성(Workload Characteristics)**: 연산 집약도(FLOPs/Byte), 정밀도 요구사항(FP32 vs INT8), 메모리 대역폭 요구 및 알고리즘 변경 빈도.
- **가속기 선정 프레임워크**: 유연성, 전력 예산, 지연 결정론(Determinism), 생산 볼륨(BEV)의 트레이드오프를 평가하여 최적의 하드웨어를 결정하는 체계.

</details>

- 정의/개념: AI 워크로드(행렬 곱셈, 비선형 활성화) 특성, 알고리즘 변경 주기, 소비 전력(TDP), 응답 지연 한도 및 생산 수량을 종합 평가하여 최적의 하드웨어 가속기를 선정하는 종합 비교 체계
- 배경/필요성: 단일 프로세서로 유연성, 처리량, 에너지 효율, NRE 비용을 동시 만족할 수 없으므로, **비즈니스 및 기술적 트레이드오프에 기반한 최적 가속기(CPU/GPU/NPU/FPGA/ASIC) 결정 필수**

#### 한줄 요약

- **유연성·처리량·에너지 효율(TOPS/W)·NRE 비용** 트레이드오프 기반 AI 가속기 선정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Workload Fit(워크로드 적합성)**: 딥러닝 연산자들을 가속기 하드웨어에 CPU 폴백 없이 온전히 매핑할 수 있는 호환성 비율.
- **Effective TOPS(실효 연산 성능)**: 이론적 피크 스펙이 아닌, 메모리 병목 및 장치 간 통신 오버헤드를 반영한 실제 달성 처리 성능.
- **TCO(Total Cost of Ownership)**: 칩 구매/개발 단가(NRE)와 전력 소비, 쿨링 비용, 소프트웨어 유지보수비를 합산한 총 수명주기 비용.

</details>

- 하드웨어 연산자 매핑률을 근본적으로 좌우하는 딥러닝 **실모델 적합성(Workload Fit)** 평가 필수
- 단순 피크 스펙(TOPS)을 배제하고 메모리 병목 및 CPU 폴백 지연을 포함한 **실효 성능(Effective Performance)** 기준 비교
- 초기 설계/마스크 비용(NRE)과 운영 전력(TDP)을 종합적으로 고려하는 **수명주기 총비용(TCO)** 분석 수행

#### 한줄 요약

- **워크로드 적합성(Workload Fit)·실효 성능(Effective TOPS)·TCO(수명주기 비용)** 종합 평가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Host CPU**: 운영체제 실행, 전처리/후처리, 시스템 제어 및 미지원 연산자 폴백을 전담하는 중앙 처리 장치.
- **AI 컴파일러/런타임**: ONNX, PyTorch 그래프를 각 가속기 타깃 기계어로 변환하고 텐서 메모리 타일링을 중계하는 소프트웨어 스택.

</details>

```text
[ 이기종 AI 가속 시스템 통합 계층 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ Host CPU (시스템 제어, 데이터 전처리 및 CPU 폴백 경로)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ AI 컴파일러 / 런타임 (TVM, TensorRT, XLA, ONNX Runtime)     │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ PCIe Gen5 / CXL / NVLink ]
┌──────────────────────────────┴──────────────────────────────┐
│ AI 가속 하드웨어 계층                                        │
│  ├─ GPU  : 대규모 스레드 병렬성 (SIMT, Tensor Core, HBM3)    │
│  ├─ NPU  : 모바일 초저전력 추론 (INT8 MAC Array, On-Chip SRAM)│
│  ├─ FPGA : 공간 재구성 파이프라인 (DSP Slice, BRAM, LUTs)    │
│  └─ ASIC : 뼛속까지 고정된 도메인 특화 회로 (TPU MXU, 2D Array)│
└─────────────────────────────────────────────────────────────┘
```

선의 의미: Host CPU, AI 컴파일러/런타임, 초고속 인터커넥트(PCIe/CXL) 및 이기종 AI 가속기(GPU/NPU/FPGA/ASIC) 간의 통합 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 컴파일러 및 런타임 | 거대 연산 그래프 최적화, 텐서를 칩 사이즈에 맞춰 쪼개는 메모리 타일링 및 가속 디바이스로의 텐서 우겨넣기 맵핑 제어 |
| 호스트 중앙 처리 장치 | 전체 시스템 제어 로직, 전후처리 찌꺼기 정리 및 가속기가 뱉어낸 미지원 최신 연산의 **중앙 처리 장치 폴백** 실행 전담 |
| 그래픽, 신경망, 재구성, 주문형 가속기 | 그래픽, 엣지, 우주항공 등 각 반도체 아키텍처 고유의 물리적 하드웨어 특성에 따른 무식한 텐서 행렬 연산 집중 수행 |
| 인터커넥트 및 가속기 메모리 | 가속기가 굶어 죽지 않게 텐서 데이터 고속 스트리밍 공급 및 호스트 장치 간 피시아이이(PCIe) 톨게이트 통신 채널 제공 |

#### 한줄 요약

- **Host CPU·AI 컴파일러/런타임·PCIe/CXL 인터커넥트·온칩 메모리 & 가속 엔진**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **결정적 지연(Deterministic Latency)**: OS 지연이나 꼬리 지연(Tail Latency) 없이 정확히 고정된 클록 사이클 내에 연산을 완료하는 특성 (FPGA 강점).

</details>

```text
[ AI 가속기 선정 의사결정 파이프라인 ]
                         │
                         ▼
   [ 1. AI 알고리즘 연산 특성 및 연산 집약도(FLOPs/Byte) 분석 ]
                         │
                         ▼
   [ 2. 단순 조건 분기/제어인가, 대규모 텐서 병렬 연산인가? ]
        /                                       \
   [ 제어 집약적 (소규모) ]                  [ 대규모 텐서 병렬 연산 ]
        │                                       │
   [ CPU 확정 ]                  [ 3. 알고리즘 모델 변경 주기 분석 ]
                                         /                 \
                                 [ 잦은 변경/연구 ]     [ 고정/성숙 모델 ]
                                      │                     │
                                 [ GPU 확정 ]       [ 4. 전력·지연·수량 평가 ]
                                                     /       |       \
                                             [ 초저전력 ] [ 저지연 ] [ 대량 양산 ]
                                                 │          │          │
                                            [ NPU 확정 ] [ FPGA 확정 ] [ ASIC 확정 ]
```

**동작 원리**

1. **워크로드 분석**: 알고리즘의 연산 집약도, 메모리 바운드 여부 및 텐서 크기 측정
2. **제어/병렬 분기**: 분기 집약적 직렬 코드는 CPU에 할당, 행렬 병렬 코드는 가속기 풀로 이관
3. **알고리즘 갱신성**: 모델 구조가 매주 변경되는 학습 환경은 범용 소프트웨어 생태계를 갖춘 GPU 선정
4. **전력/지연/물량 평가**: 배터리 환경은 NPU, 서브 밀리초 결정론 저지연은 FPGA, 대규모 양산(BEV 초과)은 ASIC 확정
5. **실효 TCO 검증**: 동일 전력/환경에서 실효 성능과 수명주기 총비용(TCO)을 검증하여 최종 도입

#### 한줄 요약

- 워크로드 분석 $\to$ **제어/병렬 판정 $\to$ 갱신 주기(GPU) $\to$ 전력/지연/수량(NPU/FPGA/ASIC) 의사결정**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **가속기 5대 아키텍처 비교**:
  - CPU: 범용 OoO, 최고 유연성, 낮은 텐서 처리량
  - GPU: SIMT 병렬성, 높은 처리량, 높은 전력 (CUDA 생태계)
  - NPU: 저정밀 MAC 어레이, 초저전력 (온디바이스 모바일)
  - FPGA: 하드웨어 공간 재구성, 결정론적 초저지연 (통신/금융)
  - ASIC: 고정 논리 회로, 최고 효율(TOPS/W), 높은 NRE (대량 양산)

</details>

| 비교 항목 | CPU | GPU | NPU | FPGA | ASIC / TPU |
|:---|:---|:---|:---|:---|:---|
| 아키텍처 및 유연성 | 범용 OoO 파이프라인, 최고 유연성 | SIMT 멀티스레딩, 높은 유연성(CUDA) | 저정밀(INT8) 2D MAC 배열, 제한적 유연성 | 공간 재구성(LUT/DSP), 하드웨어 유연성 | 고정된 전용 하드와이어드 회로, 유연성 없음 |
| 전력 효율 및 성능 | 낮은 텐서 연산력 (낮은 TOPS/W) | 높은 처리량, 높은 전력 (300~700W) | 초저전력(1~5W), 높은 효율(5~15 TOPS/W) | 중간 처리량, 결정론적 초저지연(Sub-ms) | 최고 에너지 효율(TOPS/W), 최고 처리 성능 |
| 한계 및 개발 비용 | 대규모 텐서 병렬 연산 처리 한계 | 높은 전력 소모 및 인프라 비용 | 미지원 연산자 발생 시 CPU 폴백 | 복잡한 RTL 설계 및 낮은 클록 주파수 | 막대한 초기 NRE 비용 및 기능 수정 불가 |

#### 한줄 요약

- 범용/제어는 **CPU**, 대규모/유연성은 **GPU**, 모바일은 **NPU**, 저지연은 **FPGA**, 대량 양산은 **ASIC**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Memory Wall(메모리 벽)**: 연산기의 연산 속도 증가율에 비해 메모리 대역폭 증가율이 뒤처져 연산기가 데이터를 기다리며 멈추는 병목 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스펙 시트의 화려한 뻥튀기 **정점 성능**을 믿고 샀다가, 실제 내 앱을 돌리니 굼벵이가 되어버리는 참사 현상 | 절대로 벤더 말을 믿지 말고, 철저히 동일한 전력 조건 상에서 칩 밖으로 튀어나가는 핑퐁까지 합산한 종단 **실효 성능** 벤치마크 테스트 검증 | 느려터진 바깥 메모리 병목 및 굴욕적인 폴백 오버헤드가 전부 다 까발려진 진짜 내 모델의 성능 실측치 확보 |
| 칩이 모르는 듣보잡 미지원 연산자로 인해 데이터가 CPU로 강제 이탈하며 발생하는 끔찍한 텐서 핑퐁 전송 지연 | 칩을 사기 전 해당 칩의 **연산자 정밀도 지원 범위**를 뼛속까지 파헤치고, 칩이 좋아하게끔 내 코드를 뼈를 깎아 리팩토링 수행 | 칩 밖으로 데이터가 한 발짝도 나가지 못하게 봉쇄하고, 칩 내부에서 하드웨어 연산기만 온전히 돌아가는 100% 가속 오프로딩 달성 |
| 코어는 수천 개인데 메모리 퍼 오는 톨게이트(대역폭)가 좁아터져 코어들이 손가락만 빨고 노는 유휴(Starvation) 현상 | 거대 텐서를 코딱지만 한 타일로 쪼개고, 칩 내부 창고(SRAM)에 넣어두어 텐서의 **데이터 재사용률**을 극한으로 끌어올리는 통제 | 바깥 메모리까지 나갈 때마다 뭉텅이로 떨어져 나가는 전기세 폭탄 전송 전력 감소 및 코어 가동률 100% 멱살잡이 달성 |
| 칩 깡통 단가 하나만 보고 제일 싼 걸 샀다가 전기세와 유지보수비로 수백억이 날아가 회사 예산이 초과 파산하는 오류 | 칩 설계부터 폐기까지 **초기 비반복 개발비**(NRE)와 칩이 평생 빨아먹을 에어컨 전기세를 모두 합친 냉혹한 **수명주기 총비용**(TCO) 평가 수행 | 가장 싸고 성능 안 떨어지는 객관적 지표를 도출하고, 중간에 생태계가 죽어서 망하지 않는 메이저 가속기 벤더 최종 생존 선택 |

#### 한줄 요약

- **실효 벤치마크 검증·연산자 커버리지 확보·온칩 SRAM 타일링·TCO 생애주기 분석**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **이기종 AI 컴퓨팅 포트폴리오**: 현대 AI 인프라는 단일 칩에 의존하지 않고, 학습용 GPU 클러스터 + 에지 추론용 NPU + 데이터 전처리 CPU를 유기적으로 결합하여 최적의 TCO 달성.

</details>

- 모델 변화가 잦은 학습/범용 환경은 **GPU**, 온디바이스 에지는 **NPU**, 통신/결정론 저지연은 **FPGA**, 초대규모 양산/데이터센터는 **ASIC 표준 채택**

#### 한줄 요약

- **알고리즘 안정성, 전력 예산, 지연 결정론, 양산 볼륨(BEV)**에 맞춘 가속기 포트폴리오 구축
