## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비균등 메모리 접근(Non-Uniform Memory Access, NUMA)**: 프로세서와 메모리의 물리적 위치에 따라 접근 지연시간과 대역폭이 비균등하게 달라지는 분산 공유 메모리 아키텍처.
- **NUMA 노드(NUMA Node)**: CPU 코어 그룹, 캐시, 독립 통합 메모리 컨트롤러(IMC)와 로컬 DRAM을 하나로 묶은 물리적 도메인.
- **메모리 경합(Memory Contention)**: 단일 전역 버스에 다수 코어의 요청이 집중되어 발생하는 대역폭 병목 및 지연 현상.

</details>

- 정의/개념: 다중 프로세서/소켓 환경에서 CPU와 메모리의 물리적 위치에 따라 접근 지연시간(Latency)과 대역폭이 비균등하게 달라지는 분산 공유 메모리 아키텍처
- 배경/필요성: 단일 공유 버스(UMA)의 **메모리 버스 경합 및 대역폭 병목을 극복하고 다중 소켓 서버의 선형적 확장성 확보**

#### 한줄 요약

- 소켓별 독립 메모리 컨트롤러를 배치하여 **로컬 저지연과 선형적 대역폭 확장** 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로컬 메모리(Local Memory)**: 명령을 실행하는 코어와 동일한 NUMA 노드에 직결되어 최소 지연으로 접근 가능한 메모리.
- **원격 메모리(Remote Memory)**: 타 노드에 속해 있어 노드 간 고속 인터커넥트(UPI/Infinity Fabric)를 경유해 접근하는 지연이 긴 메모리.
- **ccNUMA(Cache-Coherent NUMA)**: 비균등 구조 위에서 하드웨어 디렉터리 일관성 프로토콜을 결합하여 단일 가상 주소 공간을 전역 보장하는 기술.

</details>

- 소켓별 **로컬 메모리** 채널 독점 배치를 통해 프로세서 소켓 확장에 비례한 총 메모리 대역폭 선형 확장
- 타 노드의 **원격 메모리**는 **노드 간 인터커넥트**를 경유하여 로컬 대비 2~3배 긴 접근 지연 수반
- 하드웨어 레벨의 **ccNUMA** 기술을 통한 단일 가상 주소 공간 유지 및 프로그래밍 편의성 보장

#### 한줄 요약

- **로컬 메모리 우선 접근**으로 저지연을 확보하며 **ccNUMA**로 단일 주소 공간 유지

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **노드 간 인터커넥트**: Intel UPI(Ultra Path Interconnect), AMD Infinity Fabric 등 소켓 간 캐시 일관성 패킷과 원격 메모리 트랜잭션을 전송하는 고속 직렬 링크.
- **NUMA 인지 운영체제(NUMA-Aware OS)**: 프로세스 스레드와 해당 스레드가 사용하는 메모리 페이지를 동일 NUMA 노드에 바인딩하는 커널.

</details>

```text
[ ccNUMA 기반 다중 소켓 아키텍처 ]
┌────────────────────────────┐     ┌────────────────────────────┐
│ NUMA 노드 0                │     │ NUMA 노드 1                │
│  [ CPU Core 0 ~ 31 ]       │     │  [ CPU Core 32 ~ 63 ]      │
│             │              │     │             │              │
│      [ 메모리 컨트롤러 ]    │     │      [ 메모리 컨트롤러 ]    │
│             │              │     │             │              │
│     [ 로컬 DRAM (128GB) ]  │     │     [ 로컬 DRAM (128GB) ]  │
└─────────────┬──────────────┘     └─────────────┬──────────────┘
              │                                  │
              └────── [ 노드 간 고속 링크 (UPI / IF) ] ─┘
```

선의 의미: NUMA 노드 내부의 로컬 메모리와 노드 간 고속 인터커넥트(UPI/Infinity Fabric)를 통한 ccNUMA 구조도.

| 구성요소 | 책임 |
|:---|:---|
| NUMA 노드 | 독립적인 코어 그룹과 캐시, **메모리 제어기** 제공 |
| 메모리 제어기 (IMC) | 해당 노드에 결합된 로컬 물리 메모리 채널 단독 제어 |
| 노드 간 인터커넥트 | 타 노드와의 원격 메모리 접근 및 일관성 패킷 고속 전달 |
| NUMA 인지 운영체제 | 스레드 최적 배치 및 런타임 **페이지 마이그레이션** 관리 수행 |

#### 한줄 요약

- **NUMA 노드(코어+IMC+로컬DRAM)와 노드 간 고속 인터커넥트(UPI/IF)** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **First-Touch Policy**: 페이지가 처음 메모리에 할당(쓰기)될 때, 해당 쓰기 연산을 수행한 스레드가 실행 중인 로컬 노드에 페이지를 우선 배치하는 기본 정책.

</details>

```text
[ CPU 코어의 메모리 접근 요청 (Load / Store) ]
                       │
                       ▼
             [ 1. 주소 기반 홈 노드 판별 ]
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
 [ 2. 로컬 메모리 접근 ]   [ 3. 원격 메모리 접근 ]
 (동일 노드 내 IMC 경유)  (UPI/IF 고속 링크 경유 홉 이동)
             │                   │
             ▼                   ▼
 [ 최소 지연 (Low Latency) ] [ 추가 지연 (High Latency) ]
             │                   │
             └─────────┬─────────┘
                       ▼
           [ 4. 데이터 반환 및 완료 ]
                       │
                       ▼
       [ Auto NUMA: 원격 접근 빈번 시 페이지 마이그레이션 ]
```

**동작 원리**

1. **홈 노드 판별**: 요청된 물리 주소가 현재 코어의 로컬 노드인지 타 노드인지 판별
2. **로컬 접근**: 동일 노드일 경우 로컬 IMC를 통해 최저 지연으로 데이터 즉시 인출
3. **원격 접근**: 타 노드일 경우 UPI/IF 링크를 통해 원격 노드 디렉터리 및 메모리로 요청 전달
4. **페이지 마이그레이션**: 특정 스레드의 원격 접근이 반복될 경우 OS 커널이 페이지를 해당 로컬 노드로 자동 이전

#### 한줄 요약

- 홈 노드 판별 후 **로컬 즉시 접근 또는 인터커넥트 경유 원격 접근 및 마이그레이션**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **NUMA vs UMA**:
  - NUMA: 노드별 메모리 분산, 대규모 확장 가능, 위치별 지연 차이 존재
  - UMA (SMP): 단일 버스 공유, 모든 코어 접근 지연 균등, 확장성 한계

</details>

| 비교 항목 | 비균등 메모리 접근 (NUMA) | 균등 메모리 접근 (UMA / SMP) |
|:---|:---|:---|
| 적용 기준 | 2소켓 이상 엔터프라이즈 서버, 클라우드 가상화, HPC 클러스터 | 단일 소켓 PC, 모바일 AP, 소형 임베디드 시스템 |
| 핵심 특징 | 소켓별 독립 IMC 및 로컬 메모리, 노드 간 고속 직렬 링크(UPI) | 모든 CPU가 단일 시스템 버스/크로스바를 통해 동일 메모리 공유 |
| 한계 | 원격 노드 메모리 접근 시 지연시간 2~3배 증가(NUMA 비대칭성) | 코어 수 증가 시 메모리 버스 대역폭 포화 및 확장 한계 |

#### 한줄 요약

- UMA는 **동일 지연 단순성**, NUMA는 **분산 채널 기반 대규모 대역폭 확장성**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **numactl**: Linux에서 특정 프로세스나 스레드를 특정 NUMA 노드의 코어 및 메모리에 바인딩하는 제어 유틸리티.
- **Interleave 정책**: 메모리 페이지를 모든 NUMA 노드에 라운드로빈 방식으로 골고루 분산 배치하는 메모리 할당 정책.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 스레드 초기화 시 **최초 접근 정책**으로 특정 노드 메모리 포화 | 스레드 병렬 초기화 유도 및 교차 인터리브(Interleave) 할당 적용 | 전체 메모리 채널로 페이지 분산 및 대역폭 균등 활용 |
| 응용 프로그램의 원격 메모리 잦은 접근으로 트랜잭션 지연 상승 | **CPU 친화도** 및 로컬 전용 메모리 바인딩 고정 설정 적용 | 불필요한 원격 접근 억제 및 서비스 지연시간 안정화 |
| **자동 NUMA 균형** 가동 시 페이지가 지속적으로 오가는 **재배치 진동** 발생 | 이동 임계치 세부 조율 및 대형 시스템에선 자동 기능 명시적 비활성화 | 불필요한 노드 간 메모리 데이터 이사 트래픽 원천 차단 |
| 데이터베이스 공유 버퍼가 원격에 배치되어 초당 쿼리 처리량 하락 | 응용 소프트웨어 차원의 파티셔닝 및 **버퍼 풀 지역화** 설정 도입 | 데이터 로컬 적중률 상향으로 시스템 메모리 처리량 극대화 |

#### 한줄 요약

- **numactl 바인딩·인터리브 할당·Auto NUMA 튜닝·버퍼 풀 지역화**로 지연 극소화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL(Compute Express Link) 기반 NUMA**: CXL 메모리 확장기를 통해 PCIe/CXL 버스로 이종 메모리 풀을 결합하여 NUMA 계층을 한 단계 더 확장하는 차세대 기술.

</details>

- 워크로드 특성 분석 기반 **독립 태스크는 CPU/메모리 노드 바인딩, 대규모 공유 데이터는 Interleave 정책 적용**

#### 한줄 요약

- **스레드 친화도와 메모리 페이지 지역성 최적화**를 통한 NUMA 성능 극대화
