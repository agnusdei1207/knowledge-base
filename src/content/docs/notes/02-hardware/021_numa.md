## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비균등 메모리 접근(Non-Uniform Memory Access)**: 프로세서와 메모리의 상대적 물리 위치에 따라 접근 지연시간과 대역폭이 비균등하게 달라지는 공유 메모리 아키텍처이다.
- **NUMA 노드(NUMA Node)**: 코어 그룹, 캐시, 독점 메모리 제어기를 하나로 묶어 독립 제어하는 물리적 도메인 단위이다.
- **메모리 경합(Memory Contention)**: 단일 전역 버스에 다수 코어의 요청이 몰려 신호 지연 및 접근 병목이 일어나는 현상이다.

</details>

- 정의: 프로세서와 메모리를 다수의 **NUMA 노드**로 분할하여 접근 위치에 따라 지연시간 차이가 발생하는 **비균등 메모리 접근** 아키텍처
- 배경: 다중 소켓 환경에서 단일 공유 버스의 **메모리 경합**과 대역폭 한계를 극복하고 확장을 지원하기 위함

#### 한줄 요약

- 소켓별 독립 메모리 제어기를 배치하여 지연 차이를 허용하면서 전체 메모리 대역폭과 확장성을 극대화하는 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로컬 메모리(Local Memory)**: 명령을 실행 중인 코어와 동일한 노드 내부에 위치하여 지연 없이 접근 가능한 메인 메모리이다.
- **원격 메모리(Remote Memory)**: 타 노드에 속해 있어 노드 간 인터커넥트를 우회하여 접근해야 하는 메모리이다.
- **ccNUMA(Cache-Coherent NUMA)**: 비균등 구조 위에서 하드웨어 일관성 프로토콜을 결합하여 단일 가상 공간을 전역 보장하는 기술이다.
- **노드 간 인터커넥트(Inter-Node Interconnect)**: 노드 사이에서 원격 메모리 접근 및 일관성 패킷을 초고속으로 전송하는 직렬 링크이다.

</details>

- 소켓별로 **로컬 메모리** 채널을 독점 배치하여 프로세서 확장에 비례해 총 대역폭이 확장됨.
- 타 노드의 **원격 메모리**는 **노드 간 인터커넥트**를 경유하여 더 긴 접근 지연을 수반함.
- 하드웨어 레벨의 **ccNUMA** 기술을 통해 분산 환경에서도 단일 가상 주소 공간을 전역적으로 유지함.

#### 한줄 요약

- 로컬 메모리 우선 접근으로 저지연을 확보하며, 시스템 규모에 맞게 대역폭을 확장하면서도 단일 주소 공간을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: 프로세서 소켓 내부에 통합 탑재되어 메모리 접근 트랜잭션을 제어하는 하드웨어 모듈이다.
- **NUMA 인지 운영체제(NUMA-Aware OS)**: 스레드와 물리 페이지 할당을 동일 노드로 바인딩하여 관리하는 운영체제 커널이다.
- **페이지 마이그레이션(Page Migration)**: 런타임에 접근 패턴을 관찰하여 원격 접근이 잦은 페이지를 로컬 노드로 자동 이동시키는 기능이다.

</details>

```text
[ ccNUMA 기반 다중 소켓 아키텍처 ]
+----------------------------+     +----------------------------+
| NUMA 노드 0                |     | NUMA 노드 1                |
|  [ 프로세서 코어 그룹 ]    |     |  [ 프로세서 코어 그룹 ]    |
|             │              |     |             │              |
|      [ 메모리 제어기 ]     |     |      [ 메모리 제어기 ]     |
|             │              |     |             │              |
|     [ 로컬 물리 메모리 ]   |     |     [ 로컬 물리 메모리 ]   |
+-------------┬--------------+     +-------------┬--------------+
              │                                  │
              └────── [ 노드 간 인터커넥트 ] ──────┘
```

| 구성요소 | 책임 |
|:---|:---|
| **NUMA 노드** | 독립적인 코어 그룹과 캐시, **메모리 제어기** 제공 |
| **메모리 제어기** | 해당 노드에 결합된 로컬 물리 메모리 채널 단독 제어 |
| **노드 간 인터커넥트** | 타 노드와의 원격 메모리 접근 및 일관성 패킷 고속 전달 |
| **NUMA 인지 운영체제** | 스레드 최적 배치 및 런타임 **페이지 마이그레이션** 관리 수행 |

#### 한줄 요약

- 독립된 노드와 통합 메모리 제어기, 이를 연결하는 고속 인터커넥트 및 운영체제 스케줄러가 유기적 계층을 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **CPU 친화도(CPU Affinity)**: 특정 스레드가 지정된 노드의 코어 세트에서만 바인딩되어 실행되도록 고정하는 스케줄링 설정이다.
- **홈 노드(Home Node)**: 해당 물리 주소 페이지의 실제 메모리가 물리적으로 꽂혀있는 기준 노드이다.
- **원격 메모리 요청(Remote Memory Request)**: 로컬 노드가 아닌 타 노드의 디렉터리 및 메모리로 링크를 통해 전달되는 접근 패킷이다.

</details>

```text
[ 코어 내 메모리 접근 요청 발생 ]
               │
               ▼
       [ 1. 홈 노드 판별 ]
               │
      ┌────────┴────────┐
      ▼                 ▼
[ 2. 로컬 접근 ]  [ 3. 원격 접근 ]
      │                 │
      ▼                 ▼
[ 로컬 대역폭 ]   [ 통신망 홉 경유 ]
      │                 │
      └────────┬────────┘
               ▼
       [ 4. 데이터 반환 ]
               │
               ▼
[ 원격 비율 검사 및 페이지 이동 ]
```

### 동작 원리

1. 홈 노드 판별: 요청한 물리 주소가 속한 **홈 노드**를 하드웨어적으로 판별함.
2. 로컬 접근: 동일 노드이면 로컬 메모리 제어기를 통해 지연 없이 고속으로 접근함.
3. 원격 접근: 타 노드이면 인터커넥트를 통해 **원격 메모리 요청** 패킷을 전달함.
4. 데이터 반환 및 이동: 접근 후 원격 비율이 지속적으로 높으면 **페이지 마이그레이션**을 수행함.

#### 한줄 요약

- 주소의 홈 노드를 판별하여 로컬 및 원격 접근으로 분기하고, 빈도에 따라 페이지 마이그레이션 최적화를 단행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **균등 메모리 접근(Uniform Memory Access)**: 단일 전역 버스를 사용하여 어떤 코어에서 접근하든 메모리 지연시간이 동일한 아키텍처이다.
- **다중 소켓(Multi-Socket)**: 메인보드 상에 여러 개의 독립 프로세서 소켓을 탑재하여 전체 연산 용량을 늘리는 플랫폼이다.
- **배치 민감도(Placement Sensitivity)**: 스레드와 페이지 할당 위치에 따라 전체 애플리케이션 성능이 심하게 요동치는 성질이다.

</details>

| 비교 항목 | 비균등 메모리 접근 (NUMA) | 균등 메모리 접근 (UMA) |
|:---|:---|:---|
| 메모리 접근 지연 | 접근 위치에 따른 로컬 및 원격 지연 차이 발생 | 모든 코어가 동일하고 균등한 접근 지연 공유 |
| 시스템 확장성 | 분산 채널 구조를 통해 용량 및 대역폭 확장 용이 | 단일 버스 경합 및 포화로 대규모 확장 한계 |
| 총 메모리 대역폭 | 노드 증설에 비례하여 선형적으로 대역폭 증가 | 공유 매체 한계로 전체 대역폭 증가에 한계 노출 |
| 소프트웨어 민감도 | 성능이 요동치는 **배치 민감도**가 매우 높아 최적화 필수 | 운영체제 스케줄러가 어느 코어든 임의 조율 가능 |
| 주요 적용 환경 | 다중 소켓 기반 대규모 엔터프라이즈 및 클라우드 서버 | 단일 소켓 모바일 칩, 소형 PC 및 임베디드 장비 |

#### 한줄 요약

- 비균등 접근(NUMA)은 지연 차이의 대가로 뛰어난 확장성을 제공하며, 균등 접근(UMA)은 균등함을 제공하나 확장성에 한계가 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최초 접근 정책(First-Touch Policy)**: 페이지를 메모리에 처음 쓴 스레드가 위치한 노드에 해당 페이지를 할당하는 기본 정책이다.
- **자동 NUMA 균형(Automatic NUMA Balancing)**: 운영체제가 폴트 통계를 분석해 스레드와 페이지를 동일 노드로 당기는 동기화 기능이다.
- **재배치 진동(Placement Oscillation)**: 다중 스레드가 데이터를 동시 접근할 때 페이지가 노드 사이를 무한히 오가며 오버헤드를 일으키는 현상이다.
- **버퍼 풀 지역화(Buffer Pool Localization)**: 데이터베이스가 캐시 풀을 특정 노드 전용으로 할당하여 적중 시 로컬 메모리만 읽게 하는 튜닝 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 스레드 초기화 시 **최초 접근 정책**으로 특정 노드 메모리 포화 | 스레드 병렬 초기화 유도 및 교차 인터리브(Interleave) 할당 적용 | 전체 메모리 채널로 페이지 분산 및 대역폭 균등 활용 |
| 응용 프로그램의 원격 메모리 잦은 접근으로 트랜잭션 지연 상승 | **CPU 친화도** 및 로컬 전용 메모리 바인딩 고정 설정 적용 | 불필요한 원격 접근 억제 및 서비스 지연시간 안정화 |
| **자동 NUMA 균형** 가동 시 페이지가 지속적으로 오가는 **재배치 진동** 발생 | 이동 임계치 세부 조율 및 대형 시스템에선 자동 기능 명시적 비활성화 | 불필요한 노드 간 메모리 데이터 이사 트래픽 원천 차단 |
| 데이터베이스 공유 버퍼가 원격에 배치되어 초당 쿼리 처리량 하락 | 응용 소프트웨어 차원의 파티셔닝 및 **버퍼 풀 지역화** 설정 도입 | 데이터 로컬 적중률 상향으로 시스템 메모리 처리량 극대화 |

#### 한줄 요약

- 정책 우회 교차 할당, 스레드 친화도 바인딩, 재배치 억제 및 응용 수준 지역화를 통해 성능 저하를 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NUMA 튜닝 프레임워크(NUMA Optimization Framework)**: 하드웨어 토폴로지 분석, 커널 바인딩, 버퍼 파티셔닝을 결합하여 로컬 적중률을 극대화하는 실무 가이드라인이다.

</details>

- 공유 데이터가 적으면 로컬 바인딩을 적용하고, 노드 간 공유가 크면 교차 분산을 선택하여 균형을 맞춤

#### 한줄 요약

- 원격 접근으로 인한 지연 한계를 인지하고 응용 프로그램 특성에 맞춘 스레드와 페이지 배치 최적화를 필수적으로 수행해야 한다.
