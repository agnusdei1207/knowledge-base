## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비균등 메모리 접근(Non-Uniform Memory Access, NUMA)**: 프로세서와 메모리의 물리적 위치에 따라 접근 지연과 대역폭이 달라지는 공유 메모리 구조입니다.
- **NUMA 노드(NUMА Node)**: 코어, 메모리 제어기, 로컬 메모리를 묶은 물리적 지역입니다.
- **로컬 메모리(Local Memory)**: 요청 코어와 같은 NUMA 노드에 연결된 메모리입니다.

</details>

- 정의/개념: 프로세서 코어와 메모리의 물리적 거리에 따라 접근 지연시간과 대역폭이 달라지는 **비균등 분산 공유 메모리 아키텍처**
- 배경/필요성: 단일 공유 버스(UMA) 구조만으로는 **다중 소켓 환경의 메모리 대역폭 포화 및 확장 한계 극복 불가**

#### 한줄 요약

- NUMA에서는 모든 메모리가 하나처럼 보이지만, 가까운 메모리를 쓰는지 먼 메모리를 쓰는지에 따라 실제 속도가 달라집니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **원격 메모리(Remote Memory)**: 요청 코어와 다른 노드에 있어 노드 간 연결망을 거쳐 접근하는 메모리입니다.
- **캐시 일관성 NUMA(Cache-Coherent NUMA, ccNUMA)**: NUMA 구조에서 캐시 일관성 프로토콜로 공유 주소 공간을 유지하는 방식입니다.
- **메모리 지역성(Memory Locality)**: 작업과 데이터가 같은 노드에 배치되어 접근 비용이 낮은 상태입니다.

</details>

- 노드별 채널로 **메모리 대역폭 확장**
- 원격 접근에 따른 **지연·대역폭 비대칭**
- ccNUMA 기반 **공유 주소 공간 유지**

#### 한줄 요약

- 노드를 늘리면 메모리 채널도 늘지만, 스레드와 데이터를 가까이 배치하지 않으면 원격 연결망이 병목이 됩니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **노드 간 인터커넥트(Node Interconnect)**: NUMA 노드 사이에 데이터, 메모리, 일관성 요청을 전달하는 연결망입니다.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 노드의 메모리 채널 요청을 관리하는 제어기입니다.
- **NUMA 인지 운영체제(NUMА-Aware OS)**: 스레드와 메모리 페이지의 노드 배치를 인식해 조정하는 운영체제입니다.

</details>

```text
[NUMA 시스템]
├─ 노드 0
│  ├─ 코어 그룹
│  ├─ IMC
│  └─ 로컬 메모리
├─ 노드 1
│  ├─ 코어 그룹
│  ├─ IMC
│  └─ 로컬 메모리
└─ 노드 간 인터커넥트
```

| 구성요소 | 책임 |
|:---|:---|
| NUMA 노드 | 코어와 로컬 메모리의 지역 실행 제공 |
| IMC | 로컬 메모리 채널 제어 |
| 노드 간 인터커넥트 | 원격 데이터와 일관성 메시지 전달 |
| NUMA 인지 운영체제 | 스레드·페이지 지역성 관리 |

#### 한줄 요약

- 각 노드는 자기 코어와 메모리를 빠르게 연결하고, 인터커넥트는 노드 사이의 원격 접근을 담당합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 마이그레이션(Page Migration)**: 접근 패턴에 맞춰 메모리 페이지를 다른 NUMA 노드로 옮기는 처리입니다.
- **First-Touch 정책(First-Touch Policy)**: 페이지를 처음 실제로 접근한 실행 노드에 배치하는 정책입니다.

</details>

```text
[1. 코어의 메모리 요청]
          │
          ▼
[2. 주소의 홈 노드 확인]
          │
          ├─ 로컬 → [3. 로컬 IMC 접근]
          │
          └─ 원격 → [3. 인터커넥트 경유 접근]
                              │
                              ▼
                         [4. 데이터 반환·배치 조정]
```

**동작 원리**
1. **코어의 메모리 요청**: 실행 스레드가 주소를 참조
2. **주소의 홈 노드 확인**: 주소가 속한 메모리 노드 판정
3. **로컬 IMC 접근 또는 인터커넥트 경유 접근**: 위치별 데이터 요청 수행
4. **데이터 반환·배치 조정**: 결과 반환과 필요 시 페이지 마이그레이션

#### 한줄 요약

- 운영체제는 요청 주소의 노드를 확인해 가까우면 직접 접근하고, 멀면 연결망을 거치며 반복 원격 접근은 배치를 바꿀 수 있습니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **NUMA(Non-Uniform Memory Access)**: 메모리가 노드별로 분산되어 접근 지연이 불균일하나 확장이 용이한 구조.
- **UMA(Uniform Memory Access)**: 모든 코어가 공유 버스를 통해 동일한 지연으로 메모리에 접근하는 대칭형 구조.

</details>

| 메모리 구조 | NUMA | UMA |
|:---|:---|:---|
| 적용 기준 | 다중 소켓과 대규모 메모리 확장 | 소규모 시스템의 균일한 접근 필요 |
| 핵심 특징 | 노드별 로컬 채널과 원격 연결 | 모든 코어가 유사한 메모리 비용 공유 |
| 한계 | 원격 지연과 지역성 관리 부담 | 공유 채널과 메모리 확장 한계 |

#### 한줄 요약

- UMA는 위치를 신경 쓰기 쉽고 NUMA는 규모를 키우기 좋지만, NUMA에서는 배치가 성능을 좌우합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 친화도(CPU Affinity)**: 스레드가 실행될 수 있는 코어 또는 노드 범위를 제한하는 설정입니다.
- **인터리브 할당(Interleave Allocation)**: 페이지를 여러 NUMA 노드에 분산해 배치하는 메모리 정책입니다.
- **버퍼 풀 지역화(Buffer Pool Locality)**: 데이터베이스 버퍼와 이를 사용하는 스레드를 같은 노드에 배치하는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 한 노드에만 페이지가 몰려 대역폭 포화 | 병렬 초기화와 인터리브 할당 적용 | 노드별 채널 활용 균형 |
| 스레드가 원격 페이지를 반복 접근 | CPU 친화도와 페이지 바인딩 적용 | 원격 지연과 인터커넥트 트래픽 감소 |
| 자동 마이그레이션이 페이지를 반복 이동 | 이동 임계값과 배치 정책 조정 | 불필요한 페이지 이동 감소 |
| 공유 버퍼가 원격 노드에 배치 | 버퍼 풀과 작업 스레드 지역화 | 데이터 접근 지연 완화 |

#### 한줄 요약

- NUMA 최적화는 코어 고정만으로 끝나지 않으며, 실제 데이터 페이지와 작업 스레드의 위치를 함께 맞추는 작업입니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **원격 접근 비율(Remote Access Ratio)**: 전체 메모리 접근 중 다른 NUMA 노드로 나간 접근의 비율입니다.

</details>

- 독립 워크로드는 **노드별 고정 바인딩**, 전역 공유는 **인터리브 할당** 선택

#### 한줄 요약

- NUMA의 핵심 판단은 코어 수가 아니라, 작업이 필요한 데이터를 자기 노드에서 얼마나 자주 얻는지입니다.
