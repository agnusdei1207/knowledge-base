## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비균등 메모리 접근(Non-Uniform Memory Access, NUMA)**: 다중 프로세서 시스템에서 프로세서 코어와 메모리의 물리적 위치(소켓/노드)에 따라 메모리 접근 지연시간과 대역폭이 상이한 분산 공유 메모리 구조.
- **NUMA 노드(NUMA Node)**: CPU 코어 그룹, 사설 캐시, 통합 메모리 제어기(IMC), 로컬 DRAM 채널이 결합된 독립적인 물리적 컴퓨팅 단위.
- **로컬 메모리(Local Memory)**: 해당 프로세서 코어와 동일한 NUMA 노드에 직접 장착되어 인터커넥트 경유 없이 최단 지연시간으로 접근 가능한 메모리.

</details>

- 정의/개념: 프로세서 코어가 자신의 노드에 직결된 로컬 메모리와 타 노드의 원격 메모리를 단일 공유 주소 공간으로 매핑하되 접근 지연이 달라지는 **NUMA(Non-Uniform Memory Access) 아키텍처**
- 배경/필요성: 단일 공유 버스 기반 대칭형(UMA) 구조에 따른 **다중 소켓 확장 시 메모리 버스 대역폭 포화 및 확장 한계 극복**

#### 한줄 요약
- NUMA는 메모리를 소켓별로 분산 배치하여 대역폭을 확장하되, 로컬과 원격 접근 간의 지연시간 비대칭성을 소프트웨어와 하드웨어로 최적화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **원격 메모리(Remote Memory)**: 타 프로세서 소켓(노드)에 연결되어 점대점 인터커넥트(UPI/Infinity Fabric)를 경유해야 접근 가능한 상대 노드의 메모리.
- **캐시 일관성 NUMA(Cache-Coherent NUMA, ccNUMA)**: 하드웨어 디렉터리 기반 일관성 프로토콜을 통해 분산된 NUMA 노드 간에도 단일 공유 메모리 주소 공간과 데이터 일치성을 보장하는 구조.
- **메모리 지역성(Memory Locality)**: 실행 중인 스레드와 해당 스레드가 참조하는 메모리 페이지를 동일한 NUMA 노드에 인접 배치하여 원격 트랜잭션을 최소화하는 성질.

</details>

- 메모리 대역폭 선형 확장: 노드마다 독립된 **통합 메모리 제어기(IMC)** 및 DRAM 채널을 두어 코어 수 증가에 비례하여 시스템 총 대역폭 확장
- 지연시간 및 대역폭 비대칭성: 로컬 메모리 접근 대비 **원격 메모리(Remote Memory)** 접근 시 점대점 인터커넥트 홉(Hop) 경유로 인해 2~3배의 지연시간 발생
- 단일 주소 공간 유지: **ccNUMA** 기술을 통해 물리 메모리는 분산되어 있어도 OS와 응용 프로그램에는 단일한 연속 공유 주소 공간으로 투명하게 제공

#### 한줄 요약
- NUMA는 노드별 독립 메모리 채널로 대역폭을 확장하며, 스레드와 데이터의 지역성(Locality) 최적화가 시스템 성능을 좌우한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **노드 간 인터커넥트(Inter-Node Interconnect)**: Intel UPI(Ultra Path Interconnect), AMD Infinity Fabric 등 NUMA 소켓 간에 패킷화된 데이터와 캐시 일관성 메시지를 고속 전송하는 점대점 링크.
- **통합 메모리 제어기(Integrated Memory Controller, IMC)**: 프로세서 다이에 내장되어 로컬 DDR 채널 스케줄링 및 원격 인터커넥트 요청 중재를 전담하는 유닛.
- **NUMA 인지 운영체제(NUMA-Aware OS)**: 스레드 스케줄링 및 가상 메모리 페이지 할당 시 NUMA 토폴로지를 인식하여 로컬 노드 우선 배치를 강제하는 OS 커널.

</details>

```text
[NUMA 다중 소켓 시스템 아키텍처]
 ┌───────────────── [ NUMA 노드 0 (소켓 0) ] ─────────────────┐
 │  CPU 코어 클러스터 ── L1/L2 캐시 ── 공유 L3 캐시 (LLC)        │
 │                                 │                         │
 │                    통합 메모리 제어기 (IMC 0)              │
 │                     ├─ 로컬 DRAM 채널 (로컬 메모리 0)      │
 │                     └─ [디렉터리 제어기]                  │
 └─────────────────────────────────┬─────────────────────────┘
                                   │
                    [ 점대점 고속 인터커넥트 (UPI / Infinity Fabric) ]
                                   │
 ┌─────────────────────────────────┴─────────────────────────┐
 │                    통합 메모리 제어기 (IMC 1)              │
 │                     ├─ 로컬 DRAM 채널 (로컬 메모리 1)      │
 │                     └─ [디렉터리 제어기]                  │
 │                                 │                         │
 │  CPU 코어 클러스터 ── L1/L2 캐시 ── 공유 L3 캐시 (LLC)        │
 └───────────────── [ NUMA 노드 1 (소켓 1) ] ─────────────────┘
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 인터커넥트는 독립된 소켓 간의 원격 메모리 및 일관성 트랜잭션을 연결함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **NUMA 노드** | 단일 CPU 소켓 | 코어군, 캐시 계층, 로컬 DRAM의 독립 연산 환경 제공 | 독립 전원/클록 도메인 |
| **통합 메모리 제어기** | 프로세서 다이 내장 | 로컬 메모리 요청 처리 및 원격 인터커넥트 패킷 변환 | 다채널 DDR 스케줄러 |
| **점대점 인터커넥트** | 소켓 간 전용 링크 | 노드 간 데이터 전송 및 **디렉터리 기반 캐시 일관성** 중계 | Intel UPI, AMD xGMI |
| **NUMA 인지 OS** | 운영체제 커널 | 스레드 친화도(Affinity) 및 메모리 정책(First-Touch) 통제 | Linux numactl / libnuma |

#### 한줄 요약
- NUMA 시스템은 노드별 코어+IMC+로컬 메모리와 이들을 엮는 점대점 인터커넥트 및 NUMA 인지 OS로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **First-Touch 정책(First-Touch Policy)**: 가상 메모리 페이지 할당 시 메모리를 최초로 읽거나 쓴 스레드가 속한 로컬 NUMA 노드에 물리 프레임을 우선 배치하는 기본 OS 정책.
- **페이지 마이그레이션(Page Migration)**: 특정 페이지에 대한 원격 노드의 접근 빈도가 로컬 접근보다 높아질 때 해당 물리 페이지를 원격 노드의 메모리로 동적 이전하는 최적화 기법.

</details>

```text
1. 코어의 메모리 주소(물리 주소 PA) 접근 요청
                      │
                      ▼
2. 주소 디코더가 해당 물리 주소의 홈 노드(Home Node) 판정
   ┌──────────────────┴──────────────────┐
[ 로컬 NUMA 노드 주소 ]               [ 원격 NUMA 노드 주소 ]
   │                                     │
   ▼                                     ▼
3. 로컬 IMC 즉시 접근                 4. 점대점 인터커넥트(UPI) 패킷 발행
   (로컬 DRAM 버스 읽기)                 │
   │                                     ▼
   │                                  5. 원격 노드 IMC 경유 DRAM 데이터 인출
   │                                     │
   │                                     ▼
   │                                  6. 인터커넥트 응답 수신 (지연시간 $2\sim 3\times$)
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 코어로 데이터 반환 (필요 시 OS AutoNUMA가 페이지 마이그레이션 스케줄링)
```

분기 결과: **로컬 메모리 접근은** 수십 나노초 내에 즉시 완료되나, **원격 메모리 접근은** 인터커넥트 패킷 왕복으로 인해 지연시간과 대역폭 손실이 발생함

#### 한줄 요약
- 주소 판정 후 로컬이면 직접 읽고, 원격이면 인터커넥트를 거쳐 가져오며, 지속적인 원격 접근은 페이지 마이그레이션으로 재배치한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | NUMA (Non-Uniform Memory Access) | UMA (Uniform Memory Access / SMP) |
|:---|:---|:---|
| 메모리 구성 방식 | **소켓별 독립 메모리 채널 분산 배치** | **모든 CPU가 단일 공유 시스템 버스/DRAM 공유** |
| 메모리 접근 지연 | **비균등 (로컬: 수십 ns, 원격: 백여 ns)** | **균등 (모든 코어가 동일한 접근 지연시간 보유)** |
| 시스템 확장성 | **매우 높음 (소켓 수 및 메모리 용량 선형 확장)** | 낮음 (코어 증가 시 공유 버스 대역폭 포화) |
| 소프트웨어 최적화 | **NUMA 인식 스레드 바인딩 및 메모리 배치 필수** | 별도의 지역성 고려 불필요 (단순 프로그래밍) |
| 주요 적용처 | **엔터프라이즈 멀티소켓 서버, 클라우드 가상화** | 소형 데스크톱, 스마트폰 SoC, 단일 소켓 PC |

#### 한줄 요약
- 단일 소켓의 균일성에는 UMA가 적합하고, 대규모 다중 소켓 서버의 대역폭 확장에는 NUMA가 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 친화도(CPU Affinity)**: 프로세스 또는 스레드가 지정된 특정 CPU 코어나 NUMA 노드에서만 실행되도록 스케줄러를 고정하는 설정.
- **인터리브 메모리 정책(Interleave Policy)**: 메모리 페이지를 모든 NUMA 노드에 라운드로빈 방식으로 균등 분산 할당하여 특정 노드의 메모리 대역폭 포화를 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 스레드가 초기화하여 모든 메모리가 특정 노드에 몰리는 현상 | **인터리브 할당(numactl --interleave)** 또는 병렬 초기화 | 노드 간 메모리 용량 및 채널 대역폭 균등 활용 |
| 스레드가 타 노드로 이주하여 원격 메모리 접근 지연 급증 | **CPU 친화도(numactl --cpubind / --membind) 고정** | 로컬 메모리 적중률 90% 이상 유지 및 지연 단축 |
| 대규모 공유 버퍼 풀(DB 등)에서 원격 트랜잭션 집중 | **노드별 독립 인스턴스 분할 및 NUMA 인식 버퍼 풀 구축** | 인터커넥트 트래픽 병목 완화 및 트랜잭션 처리량 극대화 |

#### 한줄 요약
- NUMA 실무 최적화는 인터리브 할당을 통한 대역폭 분산과 CPU 친화도 바인딩을 통한 로컬 메모리 적중률 극대화가 핵심이다.

## Ⅶ. 결론

- 대규모 다중 소켓 서버 시스템의 메모리 대역폭 확장을 위해 **ccNUMA 분산 공유 메모리 아키텍처를 표준 구축**하고, 비균등 지연시간 문제를 극복하기 위해 **First-Touch 정책과 CPU 친화도 바인딩 및 인터리브 메모리 할당 정책을 소프트웨어 계층에 통합 적용**하여 대규모 병렬 컴퓨팅 확장성을 극대화하는 시스템 설계 확립

#### 한줄 요약
- NUMA는 하드웨어 대역폭 확장의 핵심 기반이며, OS 및 애플리케이션의 지역성 인식 바인딩이 성능을 완성한다.
