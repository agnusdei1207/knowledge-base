## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CUDA(Compute Unified Device Architecture)**: NVIDIA GPU 기반 데이터 병렬 연산을 병렬 언어 확장으로 구현하는 생태계 및 프레임워크.
- **호스트(Host)**: CUDA 커널 및 데이터를 준비하여 GPU로 전달하고 전체 제어를 총괄하는 CPU 실행 주체.
- **장치(Device)**: CUDA 커널 인스트럭션을 병렬 처리하고 고속 가속 메모리를 제공하는 GPU 실행 주체.

- **쿠다(Compute Unified Device Architecture, CUDA)**: 엔비디아 GPU의 병렬 연산 코어를 범용 컴퓨팅(GPGPU)에 직접 프로그래밍할 수 있도록 지원하는 C/C++ 기반 병렬 소프트웨어 플랫폼.
</details>

- 정의/개념: **호스트**가 GPU **장치**의 스레드 계층과 메모리를 제어하여 커널 병렬성을 극대화하는 **CUDA** 프레임워크
- 배경/필요성: CPU 직렬 실행 방식의 대규모 텐서 병렬 연산 처리 대역폭 한계 극복 필요성

#### 한줄 요약

- CUDA는 호스트가 커널과 그리드·블록 크기를 지정하고 GPU가 다수 스레드로 데이터 병렬 연산을 실행하게 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커널(Kernel)**: GPU 스레드들이 독립 데이터 파이프라인 상에서 병렬로 구동하는 전용 함수.
- **그리드(Grid)**: 동일 커널 호출에 의해 생성되어 실행되는 전체 스레드 블록들의 최상위 묶음.
- **블록(Block)**: 동일 SM에 함께 할당되어 공유 메모리와 동기화를 활용하는 스레드 집합.
- **스레드(Thread)**: CUDA 커널 인스트럭션을 실질적으로 처리하는 최하위 연산 실행 단위.
- **병합 접근(Coalesced Access)**: 인접 스레드의 연속 메모리 요구를 단일 메모리 트랜잭션으로 통합하는 기법.
- **스트림(Stream)**: 등록된 커널 연산 및 데이터 복사 명령을 순차 실행하는 비동기 명령 큐.
- **스트림 중첩(Stream Overlapping)**: 복수의 스트림을 활용하여 커널 실행과 호스트-장치 간 데이터 전송을 동시 겹침 처리하는 기술.

</details>

- 제어와 연산을 명확히 분리하는 **호스트·장치 분리** 구조
- **그리드·블록·스레드** 3단계 계층적 병렬 작업 매핑
- 메모리 병목을 줄이는 **병합 접근** 및 **스트림 중첩** 지원

#### 한줄 요약

- 그리드·블록·스레드 계층은 병렬 작업을 배치하고, 병합 접근과 스트림 중첩은 메모리 트랜잭션과 전송 대기를 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 런타임(Host Runtime)**: 메모리 할당, 데이터 전송, 커널 런칭을 관장하는 C/C++ API 계층.
- **커널 실행 계층(Kernel Execution Hierarchy)**: 그리드를 블록 단위로 SM에 매핑하고 하위 스레드를 디스패치하는 구조.
- **장치 메모리 계층(Device Memory Hierarchy)**: 레지스터, 공유 메모리, 캐시, 전역 메모리로 구분되는 GPU 저장 체계.
- **SM(Streaming Multiprocessor)**: CUDA 스레드 블록을 수용하여 실제 SIMT 연산을 처리하는 GPU 가속 코어 집합.

</details>

```text
[호스트 런타임] -- [CUDA 스트림] -- [커널 실행 계층] -- [장치 메모리 계층]
```

선의 의미: 호스트 런타임이 CUDA 스트림 큐를 통해 커널 실행 계층 및 장치 메모리 계층을 제어하는 정적 프레임워크 관계.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 런타임 | 장치 **메모리 할당•전송•커널 실행** 관리 |
| CUDA 스트림 | 명령어 비동기 큐잉 및 연산 순서/의존성 제어 |
| 커널 실행 계층 | **SM** 상에 그리드 및 블록 스레드 병렬배치 |
| 장치 메모리 계층 | 레지스터, 공유 메모리, 전역 메모리 간 텐서 공급 |

#### 한줄 요약

- 런타임이 스트림에 작업을 등록하면 실행 계층과 메모리가 순서대로 처리한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **복사 엔진(Copy Engine)**: GPU 연산 코어와 독립적으로 DMA 기반 데이터 전송을 전담하는 HW 엔진.
- **H2D/D2H(Host-to-Device / Device-to-Host)**: CPU 메모리와 GPU 전역 메모리 간 텐서 데이터를 이송하는 방향.
- **이벤트(Event)**: 스트림 간 동기화 지점 설정 및 작업 완료 시간을 계측하는 동기화 래치.

</details>

```text
                    [호스트 병렬 작업 집합]
                               |
                   1. 스트림•의존성 등록
                               |
              +----------------------------------+
              | 병렬: 독립 CUDA 스트림          |
              | 2. 비동기 H2D 입력 복사         |
              | 3. 커널•그리드•블록 실행        |
              | 4. 이벤트 의존성 확인           |
              | 5. 비동기 D2H 결과 복사         |
              +----------------------------------+
                               |
                       [결과•완료 반환]
```

### 동작 원리

1. **스트림·의존성 등록**: CUDA 스트림 생성 및 **이벤트** 기반 동기화 순서 설정.
2. **비동기 H2D 입력 복사**: **복사 엔진**을 통해 고정 메모리 데이터를 장치로 **비동기 H2D** 전송.
3. **커널 실행**: **커널 실행 계층**에 그리드/블록 파라미터를 디스패치하여 병렬 연산 시작.
4. **완료 이벤트 기록·대기**: 커널 연산 완료 시 **이벤트** 래치를 트리거하여 후속 작업 승인.
5. **비동기 D2H 결과 복사**: 연산 결과 텐서를 **비동기 D2H** 전송으로 호스트 메모리에 반환.

#### 한줄 요약

- 각 스트림은 입력 복사·커널·결과 복사를 순서대로 실행하고, 이벤트는 스트림 사이의 선행 조건과 비동기 완료 시점을 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SYCL**: 이종 가속기 지원을 위한 오픈 표준 C++ 기반 단일 소스 병렬 프로그래밍 모델.
- **ND-range(N-Dimensional Range)**: SYCL에서 전체 글로벌 워크 아이템과 단일 워크 그룹의 배치를 정의하는 실행 범위.
- **CPU 멀티스레딩(CPU Multithreading)**: 다중 코어 상에서 OpenMP/Pthreads 등을 활용해 직렬 연산을 병렬화하는 구조.

</details>

| 병렬 프로그래밍 방식 | CUDA | SYCL | CPU 멀티스레딩 |
|:---|:---|:---|:---|
| 적용 기준 | NVIDIA GPU 하드웨어 전용 최적화 시 | 이종 하드웨어 간 크로스 플랫폼 이식성 확보 시 | 복잡한 제어 및 소규모 병렬 작업 |
| 핵심 특징 | **CUDA** 그리드-블록-스레드 매핑 | **SYCL**의 **ND-range** 모델 | **CPU 멀티스레딩** 기반 태스크 처리 |
| 한계 | 특정 벤더 하드웨어 종속성 | 벤더 전용 최적화 대비 미세 성능 손실 | 제한된 스레드 수 및 대역폭 한계 |

> 요약: NVIDIA 최적화는 CUDA, 이식성은 SYCL 선택.

#### 한줄 요약

- NVIDIA GPU의 세부 기능과 도구를 활용하려면 CUDA, 여러 제조사 가속기에서 같은 C++ 모델을 유지하려면 SYCL이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **전역 동기화(Global Synchronization)**: 모든 스트림/스레드가 멈추어 불필요한 바이어 병목을 유발하는 상태.
- **고정 호스트 메모리(Pinned Host Memory)**: 가상 메모리 페이징을 방지하여 DMA 복사 속도를 극대화하는 호스트 영역.
- **점유율(Occupancy)**: SM 연산 자원 대비 활성화된 워프 수의 비율.
- **연산 집약도(Arithmetic Intensity)**: 단위 메모리 전송 바이트당 수행하는 풋프린트 연산 수의 비율.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 **전역 동기화** 사용에 따른 스트림 병목 | **이벤트** 기반 비동기 스트림 래치 구성 | 복사 연산과 커널 연산 동시 겹침 처리 |
| Host-Device 간 메모리 복사 지연 오버헤드 | **고정 호스트 메모리** 할당 및 **스트림 중첩** 적용 | DMA 전송 속도 향상 및 대기시간 가림 |
| 비동기 커널 런칭 시 오류 추적 난항 | `cudaGetLastError()` 및 이벤트 동기화 지점 디버깅 | 정확한 오류 발생 커널 위치 도출 |
| 메모리 대역폭 포화로 인한 커널 성능 저하 | **공유 메모리** 활용 타일링 및 **연산 집약도** 제어 | 전역 메모리 통신 오버헤드 단축 |

> 사례: **공유 메모리** 기반 타일링을 통한 전역 메모리 접근 최소화

#### 한줄 요약

- 행렬 타일을 공유 메모리에서 재사용하고 여러 스트림의 복사•연산을 겹쳐 전송 병목을 줄인다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **공급자 종속(Vendor Lock-in)**: 특정 벤더 하드웨어 및 소프트웨어 생태계에 대한 구속 상태.
- **세부 최적화(Hardware-Specific Optimization)**: 타깃 반도체의 아키텍처적 특성을 100% 활용하는 하드웨어 밀착 최적화.
- **병렬 플랫폼 선택 기준(Parallel Platform Selection Criteria)**: 하드웨어 종속성 및 성능 목표에 기반한 언어/프레임워크선택 체계.

</details>

- **병렬 플랫폼 선택 기준**에 따라 NVIDIA 전용 **세부 최적화** 필요 시 **CUDA**, 범용 **이식성** 확보 시 **SYCL** 적용

#### 한줄 요약

- NVIDIA 전용 최적화의 성능·개발 도구 이득이 공급자 종속 비용보다 클 때 CUDA 선택 체계 적용.
