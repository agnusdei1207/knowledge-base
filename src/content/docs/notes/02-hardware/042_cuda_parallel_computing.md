## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CUDA(Compute Unified Device Architecture)**: NVIDIA가 개발한 GPU 범용 병렬 컴퓨팅 플랫폼이자 C/C++ 기반 프로그래밍 모델.
- **호스트-디바이스(Host-Device)**: CPU와 메인 메모리를 호스트(Host), GPU와 비디오 메모리를 디바이스(Device)로 분리하여 협업하는 구조.

</details>

- 정의/개념: GPU 하드웨어를 범용 연산(GPGPU)에 활용하기 위해 **스레드 계층(Grid-Block)** 과 메모리를 제어하는 이기종 병렬 플랫폼
- 배경/필요성: CPU 중심 코드는 대규모 데이터 병렬성을 GPU 스레드와 메모리 계층에 직접 매핑하기 어려움

#### 한줄 요약
- CPU가 커널과 데이터를 보내면 GPU가 많은 스레드로 데이터 병렬 연산을 수행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스레드 계층(Grid-Block-Thread)**: 스레드를 블록으로 묶고, 블록들을 그리드로 구성하여 대규모 병렬성을 계층적으로 관리하는 모델.
- **CUDA 스트림(CUDA Stream)**: 호스트가 디바이스에 내리는 비동기 작업(복사, 커널 실행) 큐로, 다중 스트림 시 전송과 연산이 중첩 실행됨.

</details>

- **스레드 계층 구조(그리드·블록·스레드)** 로 대규모 병렬성 추상화
- 계층형 메모리(글로벌·공유·레지스터)를 통한 수동적 메모리 최적화
- **CUDA 스트림(Stream)** 기반 비동기 데이터 전송 및 연산 오버랩 지원

#### 한줄 요약
- 그리드-블록-스레드 계층으로 코드를 짜며, 스트림을 이용해 전송과 연산을 겹쳐 실행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 함수(Kernel Function)**: `__global__` 키워드로 선언되어 GPU의 수많은 스레드에서 동시에 실행되는 C/C++ 함수.
- **공유 메모리(Shared Memory)**: `__shared__` 키워드로 선언되어 동일 블록 내 스레드들이 초고속으로 공유하는 온칩 SRAM.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 호스트 (CPU & Host RAM)                                     │
│  ├─ CUDA 런타임 API (메모리 할당, 스트림 관리, 커널 런칭)    │
│  └─ 고정 호스트 메모리 (Pinned Memory 버퍼)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │ (PCIe Gen5 / NVLink 고속 인터커넥트)
┌──────────────────────────────┴──────────────────────────────┐
│ 디바이스 (NVIDIA GPU & Device HBM/VRAM)                     │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 글로벌 메모리 (Global Memory) / L2 캐시                │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │                               │
│  ┌──────────────────────────┴────────────────────────────┐  │
│  │ 그리드 (Grid of Thread Blocks)                        │  │
│  │  ┌────────────────────────┐  ┌────────────────────────┐  │  │
│  │  │ 스레드 블록 (Block 0)   │  │ 스레드 블록 (Block N)   │  │  │
│  │  │  ├─ 공유 메모리 (SRAM) │  │  ├─ 공유 메모리 (SRAM) │  │  │
│  │  │  └─ 32스레드 워프들    │  │  └─ 32스레드 워프들    │  │  │
│  │  └────────────────────────┘  └────────────────────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트와 디바이스, 디바이스 메모리와 스레드 계층 사이의 정적 경계

| 구성요소 | 책임 |
|:---|:---|
| 호스트 런타임 드라이버 | GPU 메모리 할당, 비동기 스트림 스케줄링 및 커널 런칭 총괄 |
| 그리드 및 스레드 블록 | 1D/2D/3D 계층으로 스레드를 구조화하여 하드웨어 SM에 자동 매핑 |
| 글로벌 메모리 (Global Mem) | GPU 전체 스레드가 접근 가능한 대용량 DRAM 공간 |
| 공유 메모리 (Shared Mem) | 블록 내 스레드 간 데이터 교환 및 캐싱을 위한 사용자 제어 온칩 SRAM |
| CUDA 스트림 및 이벤트 | PCIe 전송과 커널 실행을 비동기 파이프라인으로 중첩 제어 |

#### 한줄 요약
- 호스트가 스트림으로 일감을 밀어넣으면, 디바이스의 그리드와 블록들이 메모리 계층을 활용해 계산한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **cudaMemcpyAsync**: CPU를 멈추지 않고 백그라운드 DMA를 통해 호스트와 디바이스 간 데이터를 복사하는 비동기 함수.

</details>

```text
호스트 프로그램 시작
      │
      ▼
1. 디바이스 메모리 할당
      │
      ▼
2. H2D 데이터 전송
      │
      ▼
3. 커널 실행
      │
      ▼
4. D2H 결과 수신
      │
      ▼
5. 동기화 및 해제
```

**동작 원리**

1. **메모리 할당**: GPU의 글로벌 메모리 영역에 입력 및 출력 텐서 버퍼 공간 확보
2. **H2D 데이터 전송**: 호스트 메모리의 원본 데이터를 PCIe 버스를 통해 GPU VRAM으로 복사
3. **커널 실행**: 지정된 그리드·블록 구성으로 GPU 스레드 병렬 구동
4. **D2H 결과 수신**: GPU 연산이 완료된 결과 행렬을 호스트 RAM으로 회수
5. **동기화 및 해제**: 비동기 작업 완료를 확인한 후 할당했던 GPU 디바이스 메모리 반환

#### 한줄 요약
- GPU 메모리 할당 → H2D 전송 → 커널 병렬 실행 → D2H 수신 → 동기화 및 자원 해제 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 이기종 병렬 프로그래밍 프레임워크 | CUDA | OpenCL | SYCL | OpenMP |
|:---|:---|:---|:---|:---|
| 적용 기준 | NVIDIA GPU 기반 고성능 AI/HPC | 다양한 벤더(AMD/Intel) 이종 가속기 | 모던 C++ 기반 크로스 플랫폼 가속 | 기존 C/Fortran CPU 코드 점진적 가속 |
| 핵심 특징 | NVIDIA 하드웨어 최적화·방대한 생태계 | 이기종 벤더 독립적 개방형 표준 API | 단일 소스 모던 C++ 템플릿 기반 추상화 | 컴파일러 지시어(#pragma) 기반 간편 적용 |
| 한계 | NVIDIA 전용 하드웨어 종속성(Lock-in) | 코드가 길고 저수준 API로 생산성 저하 | 벤더별 런타임 성숙도 편차 존재 | 세밀한 GPU 하드웨어 제어 및 최적화 한계 |

#### 한줄 요약
- NVIDIA 최고 성능은 CUDA, 크로스 플랫폼은 OpenCL/SYCL, 간편 병렬화는 OpenMP를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **고정 메모리(Pinned Memory)**: 페이지 아웃되지 않도록 고정해 DMA가 직접 접근할 수 있게 한 호스트 메모리.
- **커널 퓨전(Kernel Fusion)**: 연속된 작은 커널을 합쳐 런칭과 중간 메모리 접근을 줄이는 최적화.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| PCIe 대역폭 한계로 인한 **H2D 전송 병목** | 고정 메모리와 다중 스트림으로 전송·연산 중첩 | 전송 대기 노출 시간 감소 |
| 소규모 커널의 잦은 호출에 따른 런칭 오버헤드 | **커널 퓨전** 및 CUDA Graphs 적용 | 런칭 횟수와 중간 메모리 접근 감소 |
| 비연속 메모리 접근에 따른 DRAM 대역폭 낭비 | 공유 메모리 타일링(Tiling) 및 구조체 배열(SoA) 전환 | 메모리 병합(Coalescing) 달성 및 처리 속도 향상 |
| 스레드 간 데이터 동기화 경합 지연 | `__syncthreads()` 최소화 및 워프 레벨 프리미티브(`__shfl_sync`) 활용 | 동기화 대기 시간 단축 및 레지스터 직접 교환 |

#### 한줄 요약
- 고정 메모리와 스트림으로 전송을 숨기고, 커널 퓨전과 공유 메모리 타일링으로 메모리 병목을 뚫는다.

## Ⅶ. 결론

- NVIDIA GPU 기반 고성능 딥러닝/HPC 개발은 **CUDA**, 멀티 벤더 이종 환경은 **SYCL/OpenCL** 선택

#### 한줄 요약
- 프레임워크 선택 후 프로파일링으로 전송·메모리·커널 병목부터 구분해 최적화해야 한다.
