## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CUDA(Compute Unified Device Architecture)**: NVIDIA가 개발한 이기종 병렬 컴퓨팅 플랫폼이자 C/C++ 기반의 GPGPU 프로그래밍 모델.
- **호스트-디바이스 모델(Host-Device Model)**: 직렬 제어 중심의 CPU(호스트)와 대규모 병렬 연산 중심의 GPU(디바이스)가 PCIe/NVLink를 통해 협업하는 구조.

</details>

- 정의/개념: CPU(호스트)와 GPU(디바이스)의 이기종 협업 구조에서 **그리드-블록-스레드 계층과 명시적 메모리 공간**을 제어하는 **CUDA(Compute Unified Device Architecture) 병렬 컴퓨팅 모델**
- 배경/필요성: 기존 순차 언어 체계로는 **GPU 하드웨어의 수만 개 병렬 스레드 계층 사상 및 온칩 메모리 계층 제어 불가**

#### 한줄 요약
- CUDA는 GPU 하드웨어 구조를 C/C++ 언어로 직접 제어하여 대규모 병렬 연산 성능을 이끌어내는 GPGPU 플랫폼이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스레드 계층(Grid-Block-Thread Hierarchy)**: 스레드(Thread)를 스레드 블록(Block)으로 묶고, 블록들을 그리드(Grid)로 구성하여 하드웨어 SM에 계층적으로 매핑하는 구조.
- **CUDA 스트림(CUDA Stream)**: GPU 디바이스에 발행되는 비동기 명령어 큐로, 다중 스트림을 통해 호스트-디바이스 데이터 전송과 커널 실행을 동시 중첩 처리하는 메커니즘.

</details>

- 계층적 병렬 추상화: **그리드-블록-스레드(Grid-Block-Thread)** 3단계 계층을 통해 알고리즘을 하드웨어 SM 및 워프에 1:1 직관적 사상
- 프로그래머블 메모리 계층: 레지스터, 온칩 **공유 메모리(Shared Memory)**, L1/L2 캐시, 글로벌 메모리를 프로그래머가 직접 통제
- 비동기 스트림 파이프라이닝: **CUDA 스트림(Stream)**을 활용하여 PCIe 데이터 전송 지연시간을 커널 연산 시간 뒤로 완전 은닉

#### 한줄 요약
- 계층적 스레드 구조와 프로그래머블 메모리, 비동기 스트림을 통해 GPU 연산 성능을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 함수(Kernel Function)**: `__global__` 한정자로 선언되어 호스트가 런칭하고 GPU의 수많은 스레드에서 병렬 실행되는 C/C++ 함수.
- **공유 메모리(Shared Memory)**: `__shared__` 한정자로 선언되어 동일 스레드 블록 내 스레드들이 초고속으로 공유하는 온칩 SRAM.

</details>

```text
[CUDA 소프트웨어-하드웨어 매핑 계층]
 ┌─ [호스트 (CPU & 시스템 DRAM)] ── (CUDA 런타임 API / Driver)
 │   └─ 고정 메모리 (Pinned Host Memory)
 │
 ├─ [인터커넥트 버스] ────────────── PCIe Gen5 / NVLink 직결 버스
 │
 └─ [디바이스 (GPU & 글로벌 메모리)]
     ├─ 그리드 (Grid) ──► 전체 GPU 칩 매핑
     │   ├─ 스레드 블록 0 ──► SM 0 매핑 (공유 메모리 + 레지스터 할당)
     │   ├─ 스레드 블록 1 ──► SM 1 매핑
     │   └─ 스레드 블록 N ──► SM N 매핑
     │       └─ 32스레드 워프 (Warp) ──► 실행 유닛 (Tensor/CUDA Core)
     └─ [다중 CUDA 스트림 (Stream 0, 1, 2)] ──► 비동기 전송 & 커널 중첩
```

선의 의미: 가지(`├─`, `└─`)는 계층적 소속 및 하드웨어 매핑 관계; 블록 단위로 SM에 할당되어 독립 실행됨

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **호스트 런타임** | CPU 시스템 계층 | 메모리 할당(`cudaMalloc`), 스트림 관리, 커널 런칭 총괄 | C/C++ API 지원 |
| **커널 함수 (`__global__`)**| GPU 디바이스 계층 | 수만 개 스레드에서 동시 병렬 실행되는 핵심 연산 루틴 | `<<<Grid, Block>>>` 런칭 |
| **글로벌 메모리** | GPU 오프칩 DRAM (VRAM)| GPU 전역 스레드가 공유하는 대용량 데이터 저장소 | 500~1000 클록 지연 |
| **공유 메모리 (`__shared__`)**| SM 내부 온칩 SRAM | 동일 블록 내 스레드 간 초고속 데이터 교환 및 텐서 타일링 | 1~2 클록 초저지연 |
| **CUDA 스트림** | 런타임 비동기 큐 | 데이터 복사(`cudaMemcpyAsync`)와 커널 연산의 비동기 파이프라이닝 | 전송 지연 은닉 |

#### 한줄 요약
- CUDA는 호스트 런타임, 그리드-블록-스레드 계층, 글로벌/공유 메모리 및 비동기 스트림으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비동기 메모리 복사(cudaMemcpyAsync)**: CPU를 블로킹하지 않고 비동기 DMA를 통해 호스트와 디바이스 간 데이터를 고속 복사하는 API.

</details>

```text
1. 호스트: 고정 메모리(Pinned Memory) 및 GPU 글로벌 메모리 할당
                      │
                      ▼
2. 다중 CUDA 스트림 기반 파이프라인 분기
   ┌──────────────────┴──────────────────┐
[ 단일 스트림 (동기식 순차 실행) ]     [ 다중 스트림 (비동기 중첩 파이프라이닝) ]
   │                                     │
   ▼                                     ▼
3. 호스트 ➔ 디바이스 동기 복사 (전송)    3. 스트림 0: 청크 0 비동기 복사 (`cudaMemcpyAsync`)
   │ (전송 중 GPU 연산기 유휴)           │
   ▼                                     ▼
4. 커널 함수 동기 실행 (연산)            4. 스트림 0 커널 실행 ║ 스트림 1 청크 1 동기 전송 (중첩!)
   │ (연산 중 PCIe 버스 유휴)            │
   ▼                                     ▼
5. 디바이스 ➔ 호스트 동기 복사 (회수)    5. 스트림 0 결과 회수 ║ 스트림 1 커널 실행 ║ 스트림 2 전송
   └──────────────────┬──────────────────┘
                      │
                      ▼
6. `cudaStreamSynchronize()` 완료 동기화 후 자원 해제
```

분기 결과: **다중 스트림을 적용하면** PCIe 전송 시간과 GPU 커널 연산 시간이 완벽히 중첩(Overlap)되어 전체 실행 시간이 대폭 단축됨

#### 한줄 요약
- 할당 ➔ 다중 스트림 생성 ➔ 비동기 복사와 커널 연산의 동시 중첩 ➔ 결과 회수 ➔ 동기화의 6단계로 동작한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | CUDA (NVIDIA) | SYCL / DPC++ (Khronos / Intel) | OpenCL (Khronos) |
|:---|:---|:---|:---|
| 지원 하드웨어 | **NVIDIA GPU 전용 (독점 최적화)** | Intel/AMD/NVIDIA CPU, GPU, FPGA | 다중 벤더 이종 프로세서 전반 |
| 언어 및 문법 | **표준 C/C++ 확장 문법 (직관적)** | 모던 C++17/20 템플릿 기반 단일 소스 | C99 기반 저수준 C API (코드 장황) |
| 소프트웨어 생태계 | **최고 (cuDNN, TensorRT, cuBLAS 등 완성도 압도적)** | 성장 중 (oneAPI 생태계) | 보통 (라이브러리 파편화) |
| 성능 최적화 수준 | **하드웨어 아키텍처에 100% 밀착 최적화** | 중간~높음 (크로스 플랫폼 컴파일) | 중간 (휴대성은 높으나 튜닝 복잡) |
| 주요 적용처 | **전 세계 AI 딥러닝 훈련/추론 표준, HPC** | 인텔 GPU/FPGA 데이터센터 가속 | 레거시 크로스 플랫폼 임베디드 |

#### 한줄 요약
- 범용 이종 플랫폼에는 SYCL/OpenCL이 쓰이나, 최첨단 AI 및 고성능 컴퓨팅(HPC) 영역에서는 CUDA가 독보적 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **고정 메모리(Pinned/Page-Locked Memory)**: OS 페이징에 의해 스왑 아웃되지 않도록 물리 메모리에 상주시켜 DMA가 즉시 고속 접근할 수 있는 호스트 메모리.
- **커널 퓨전(Kernel Fusion)**: 연속된 여러 개의 소규모 커널을 하나의 커널로 결합하여 글로벌 메모리 읽기/쓰기를 온칩 레지스터/공유 메모리로 대체하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| PCIe 버스 대역폭 한계로 인한 호스트-디바이스 전송 병목 | **고정 메모리(Pinned Memory) 및 다중 스트림 비동기 파이프라이닝** | 데이터 전송 지연시간 100% 은닉 |
| 다수의 소규모 커널 연속 호출에 따른 런칭 오버헤드 | **커널 퓨전(Kernel Fusion) 및 CUDA Graphs 정적 그래프 런칭** | CPU-GPU 드라이버 런칭 오버헤드 90% 절감 |
| 비연속 글로벌 메모리 접근으로 인한 DRAM 대역폭 낭비 | **공유 메모리 타일링(Tiling) 및 구조체 배열(SoA) 변환** | 메모리 병합(Coalescing) 달성 및 처리량 3배 향상 |

#### 한줄 요약
- 실무에서는 고정 메모리와 다중 스트림으로 전송 지연을 은닉하고, 커널 퓨전과 공유 메모리 타일링으로 연산 효율을 극대화한다.

## Ⅶ. 결론

- 고성능 AI 딥러닝 및 병렬 컴퓨팅 환경을 구축하기 위해 **하드웨어 밀착 최적화와 cuDNN 생태계가 완비된 CUDA 플랫폼을 표준 채택**하고, 전송 병목을 극복하기 위해 **고정 메모리(Pinned Memory) 기반의 다중 스트림 비동기 파이프라이닝**을 적용하며, 런타임 오버헤드를 줄이기 위해 **커널 퓨전과 CUDA Graphs 기술**을 융합하는 고성능 GPU 가속 시스템 확립

#### 한줄 요약
- CUDA는 GPGPU 병렬 컴퓨팅의 글로벌 표준이며, 공유 메모리 타일링과 비동기 스트림 중첩을 통해 GPU 잠재력을 100% 실현한다.
