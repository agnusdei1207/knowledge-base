## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CUDA(Compute Unified Device Architecture)**: NVIDIA가 개발한 GPU 범용 병렬 컴퓨팅 플랫폼이자 C/C++ 기반 프로그래밍 모델.
- **호스트-디바이스(Host-Device)**: CPU와 시스템 메모리를 호스트, GPU와 VRAM을 디바이스로 분리하여 협업하는 이기종 연산 구조.

</details>

- 정의/개념: **호스트-디바이스** 경계를 명시적으로 다루면서 스레드 계층과 메모리를 프로그래머가 직접 제어하는 **CUDA** 플랫폼
- 배경/필요성: 기존 CPU 순차 언어 체계로는 **GPU 대규모 스레드 계층 사상과 메모리 제어 불가**

#### 한줄 요약
- CUDA는 하드웨어 구조를 추상화로 감추지 않고 코드에 명시적으로 드러내어 극단적인 병렬 성능을 얻어내는 프로그래밍 모델이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스레드 계층(Grid-Block-Thread)**: 스레드를 블록으로 묶고, 블록들을 그리드로 구성하여 대규모 병렬성을 계층적으로 관리하는 모델.
- **CUDA 스트림(CUDA Stream)**: 호스트가 디바이스에 내리는 비동기 작업 큐로, 다중 스트림 시 전송과 연산이 중첩 실행됨.

</details>

- **스레드 계층**을 기반으로 수백만 스레드를 하드웨어 자원에 계층적으로 사상
- 계층형 메모리(글로벌·공유·레지스터)를 통한 수동적 메모리 최적화
- **CUDA 스트림**을 기반으로 전송과 연산을 비동기 중첩 실행

#### 한줄 요약
- 스레드 블록만이 하드웨어 SM에 매핑되므로, 블록 크기와 자원 배분이 커널의 동시 실행 점유율을 결정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 함수(Kernel Function)**: `__global__` 키워드로 선언되어 GPU의 수많은 스레드에서 동시에 실행되는 C/C++ 함수.
- **공유 메모리(Shared Memory)**: `__shared__` 키워드로 선언되어 동일 블록 내 스레드들이 초고속으로 공유하는 온칩 SRAM.

</details>

```text
[CUDA 실행 모델]
|-- 호스트 (CPU·시스템 메모리)
|   |-- CUDA 런타임 API (할당·스트림·커널 런칭)
|   `-- 고정 메모리 버퍼
|-- 인터커넥트 (PCIe/NVLink)
`-- 디바이스 (GPU·VRAM)
    |-- 글로벌 메모리·L2 캐시
    `-- 그리드
        `-- 스레드 블록
            |-- 공유 메모리
            `-- 32스레드 워프
```

선의 의미: 계층 및 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 호스트 런타임 드라이버 | GPU 메모리 할당, 비동기 스트림 스케줄링 및 커널 런칭 총괄 |
| 그리드·스레드 블록 | 스레드를 계층으로 묶어 하드웨어 SM에 사상 |
| 글로벌 메모리 | GPU 전체 스레드가 접근 가능한 대용량 DRAM 공간 |
| **공유 메모리** | 블록 내 스레드 간 데이터 교환용 사용자 제어 고속 SRAM |
| CUDA 스트림 | 전송과 **커널 함수** 실행을 비동기 파이프라인으로 중첩 |

#### 한줄 요약
- GPU 메모리는 자동 캐싱에만 의존하지 않고 프로그래머가 명시적으로 공유 메모리에 올려 타일링할 때 최대 성능이 나온다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비동기 메모리 복사(cudaMemcpyAsync)**: CPU를 멈추지 않고 백그라운드 DMA를 통해 호스트와 디바이스 간 데이터를 복사하는 비동기 함수.

</details>

```text
호스트 프로그램 시작 → 디바이스 메모리 할당
        │
   스트림을 여러 개 쓰는가?
   ┌────┴──────────┐
아니오               예
   │                  │
동기 전송 후         전송·커널·회수를 스트림별로 겹침
커널 실행 후 회수      │
(전송 동안 연산기 유휴) │
   │             전송 지연이 다른 스트림 연산에 가려짐
   └────┬─────────────┘
        │
   완료 동기화 후 디바이스 메모리 해제
```

#### 한줄 요약
- 비동기 메모리 복사를 다중 스트림과 결합하면 호스트-디바이스 전송 지연을 다른 스트림의 커널 연산 시간 뒤로 완전히 은닉할 수 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OpenCL(Open Computing Language)**: 다양한 벤더의 CPU, GPU, DSP를 지원하는 개방형 이기종 병렬 컴퓨팅 표준.
- **SYCL**: 표준 모던 C++ 문법 기반의 단일 소스 이기종 프로그래밍 모델.

</details>

| 이기종 병렬 프로그래밍 프레임워크 | CUDA | OpenCL | SYCL | OpenMP |
|:---|:---|:---|:---|:---|
| 적용 기준 | NVIDIA GPU 기반 고성능 AI/HPC | 다양한 벤더(AMD/Intel) 이종 가속기 | 모던 C++ 기반 크로스 플랫폼 가속 | 기존 CPU 코드의 점진적 병렬 가속 |
| 핵심 특징 | NVIDIA 하드웨어 최적화·방대한 생태계 | 이기종 벤더 독립적 개방형 표준 API | 단일 소스 모던 C++ 템플릿 기반 추상화 | 컴파일러 지시어(#pragma) 기반 간편 적용 |
| 한계 | NVIDIA 전용 하드웨어 종속성(Lock-in) | 코드가 길고 저수준 API로 생산성 저하 | 벤더별 런타임 성숙도 편차 존재 | 세밀한 GPU 하드웨어 제어 및 최적화 한계 |

#### 한줄 요약
- 네 프레임워크는 성능과 이식성을 교환하는 관계이며, CUDA의 강점은 하드웨어 밀착 최적화와 cuDNN 등 상위 가속 라이브러리 생태계에 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **고정 메모리(Pinned Memory)**: 페이지 아웃되지 않도록 물리 메모리에 고정하여 DMA가 직접 고속 접근할 수 있는 호스트 메모리.
- **커널 퓨전(Kernel Fusion)**: 연속된 작은 연산 커널들을 하나로 통합하여 런칭 오버헤드와 글로벌 메모리 접근을 제거하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| PCIe 대역폭 한계로 호스트-디바이스 전송 병목 | **고정 메모리** 및 다중 스트림 파이프라인 적용 | 전송 대기 시간이 연산에 은닉되는 비율 증가 |
| 소규모 커널의 빈번한 호출로 런칭 오버헤드 누적 | **커널 퓨전** 및 CUDA Graphs 기반 실행 | 런칭 횟수 및 중간 메모리 입출력 감소 |
| 비연속 메모리 접근에 따른 DRAM 대역폭 낭비 | 공유 메모리 타일링(Tiling) 및 구조체 배열(SoA) 전환 | 메모리 병합(Coalescing) 달성 및 대역폭 활용 극대화 |
| 스레드 간 잦은 동기화로 인한 대기 지연 | `__syncthreads()` 최소화 및 워프 레벨 프리미티브 활용 | 동기화 오버헤드 제거 및 레지스터 직접 교환 |

#### 한줄 요약
- GPU 실무 성능 최적화의 본질은 연산 가속보다 호스트-디바이스 데이터 전송 은닉과 메모리 병합 처리에 있다.

## Ⅶ. 결론

- NVIDIA GPU 기반 고성능 딥러닝·HPC는 **CUDA**를 우선 채택하고, 멀티 벤더 이종 환경이 요구되면 **SYCL·OpenCL**로 이식성을 확보한 뒤 성능 격차를 실측 검증

#### 한줄 요약
- 가속 프레임워크 선택 시 생태계 성숙도와 하드웨어 종속성을 함께 평가해야 하며, 병목 프로파일링 기반의 데이터 레이아웃 최적화가 선행되어야 한다.
