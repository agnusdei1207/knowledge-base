## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CUDA(Compute Unified Device Architecture)**: NVIDIA가 개발한 GPU 병렬 컴퓨팅 플랫폼 및 C/C++ 기반 프로그래밍 모델.
- **GPGPU(General-Purpose computing on GPUs)**: 그래픽 렌더링에만 국한되던 GPU 연산 파이프라인을 범용 과학 계산 및 AI 딥러닝 연산에 활용하는 기술.

</details>

- 정의/개념: C/C++ 기반 문법 확장을 통해 수천 개의 GPU 코어와 메모리 계층을 직접 제어하여 대규모 병렬 연산을 가속하는 **GPGPU 이종 병렬 컴퓨팅 플랫폼**
- 배경/필요성: 초기 그래픽 셰이더 기반 GPGPU의 개발 난이도 및 범용 메모리 제어 한계 극복과 과학 계산 및 딥러닝 알고리즘의 GPU 코어 직관적 매핑 실현

#### 한줄 요약
- CUDA는 개발자가 친숙한 C/C++ 언어로 수천 개의 GPU 연산 코어를 직접 제어할 수 있게 해주는 GPGPU 표준 플랫폼이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **그리드-블록-스레드(Grid-Block-Thread)**: CUDA 프로그래밍의 3단계 계층 구조로, 알고리즘을 하드웨어 SM 및 워프에 직관적으로 매핑하는 가상화 단위.
- **CUDA 스트림(CUDA Stream)**: 호스트가 GPU에 발행하는 명령어(메모리 전송, 커널 실행)들의 순차적 실행 대기열로, 다중 스트림 간 비동기 중첩 지원.
- **고정 메모리(Pinned Memory)**: OS 가상 메모리 페이징에 의해 스왑 아웃되지 않고 물리 메모리에 고정되어 GPU DMA가 고속 직접 접근하는 호스트 메모리.

</details>

- **그리드-블록-스레드(Grid-Block-Thread)** 3단계 계층 모델을 통해 알고리즘 병렬성을 GPU 하드웨어(SM 및 워프)에 직관적 매핑
- 온칩 **공유 메모리(Shared Memory)**와 레지스터, 글로벌 메모리로 이어지는 다단계 메모리 계층을 개발자가 소프트웨어적으로 직접 제어
- **CUDA 비동기 스트림(Stream)**을 활용하여 호스트-디바이스 간 PCIe 데이터 전송과 커널 실행 시간을 파이프라인으로 완전 중첩

#### 한줄 요약
- 계층적 스레드 구조와 프로그래머블 메모리, 비동기 스트림을 통해 GPU 연산 성능을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **커널 함수(Kernel Function)**: `__global__` 한정자로 선언되어 호스트가 런칭하고 GPU의 수많은 스레드에서 병렬 실행되는 C/C++ 함수.
- **공유 메모리(Shared Memory)**: `__shared__` 한정자로 선언되어 동일 스레드 블록 내 스레드들이 초고속으로 공유하는 온칩 SRAM.

</details>

```text
[CUDA 병렬 컴퓨팅 아키텍처]
  │
  ├─ [호스트 서브시스템] (Host: CPU & System DRAM)
  │     ├─ [C/C++ 호스트 런타임] (커널 런칭 및 스트림 제어)
  │     └─ [고정 메모리] (Pinned DRAM, 고속 DMA 버퍼)
  │
  ├─ [호스트-디바이스 인터커넥트] (PCIe Gen5 / NVLink)
  │
  └─ [디바이스 서브시스템] (Device: GPU Core & VRAM)
        ├─ [그리드 계층] (Grid, 커널 인스턴스 블록 집합)
        ├─ [스레드 블록 계층] (Block, SM 매핑 단위)
        │     ├─ [공유 메모리] (온칩 SRAM 타일링 버퍼)
        │     └─ [배리어 동기화기] (__syncthreads 하드웨어 래치)
        ├─ [워프 실행 단위] (Warp, 32스레드 SIMT 락스텝)
        │     └─ [스레드 레지스터] (스레드별 프라이빗 레지스터)
        └─ [디바이스 메모리 계층] (글로벌 HBM/GDDR 및 공유 L2)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 (Host CPU) | 프로그램 실행 제어, 디바이스 메모리 할당 및 **비동기 커널 런칭 총괄** |
| 그리드 (Grid) | 단일 커널 실행 시 생성되는 **1D/2D/3D 스레드 블록들의 전체 집합** |
| 스레드 블록 (Block) | 단일 SM에 할당되어 **공유 메모리와 배리어 동기화를 통해 협력 실행** |
| 워프 (Warp) | 32개의 스레드가 단일 명령어로 묶여 SM 연산 유닛에서 **SIMT 방식으로 실행** |
| 공유 메모리 | 동일 블록 내 스레드들이 1사이클 내에 접근하는 **프로그래머블 온칩 SRAM 버퍼** |

#### 한줄 요약
- CUDA는 호스트 제어 하에 그리드, 스레드 블록, 워프, 공유 메모리 계층을 하드웨어 SM과 매핑하여 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **cudaMemcpyAsync**: 비동기 메모리 복사 함수로 호스트 CPU가 블로킹되지 않고 다음 명령어를 즉시 발행 가능.
- **스트림 동기화(Stream Synchronization)**: 비동기로 발행된 커널 연산 및 데이터 전송 작업이 모두 끝날 때까지 대기하는 제어 기법.

</details>

```text
+-------------------------------------------------------------+
|        호스트 메모리 할당 및 고정 메모리(Pinned) 데이터 준비  |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       1. CUDA 다중 스트림 생성 및 비동기 파이프라인 구성    |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       2. 비동기 HtoD 메모리 복사 (cudaMemcpyAsync) 디스패치 |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       3. GPU 커널 함수 런칭 및 SM 워프 동시 병렬 연산       |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       4. 연산 완료 청크의 DtoH 비동기 복사 및 전송 중첩      |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       5. 스트림 동기화(cudaStreamSynchronize) 및 결과 수합  |
+-------------------------------------------------------------+
```

분기 결과: **단일 스트림** 사용 시 전송과 연산이 직렬화되어 버스 대기 지연이 누적되나, **다중 비동기 스트림** 적용 시 전송 지연시간이 연산 시간 뒤로 100% 은닉되어 처리량이 배가됨

**동작 원리**

1. **고정 메모리 및 스트림 초기화**: 페이징 불가능한 고정 메모리(Pinned Memory)를 할당하여 DMA 접근성을 확보하고, 독립적인 작업 큐인 다중 CUDA 스트림 생성
2. **비동기 호스트-디바이스 복사**: `cudaMemcpyAsync`를 호출하여 CPU 블로킹 없이 입력 데이터 청크를 GPU 글로벌 메모리로 즉시 비동기 전송
3. **그리드 매핑 및 커널 병렬 연산**: GPU 하드웨어 스케줄러가 블록들을 SM에 분배하고 32스레드 워프 단위로 SIMT 병렬 연산 개시
4. **전송 및 연산 동시 중첩(Overlap)**: 복사 엔진과 연산 엔진이 독립 작동하여, 스트림 1의 연산이 수행되는 동안 스트림 2의 데이터 전송이 병렬로 동시 진행
5. **비동기 반환 및 스트림 동기화**: 연산이 끝난 결과를 호스트로 비동기 회수하고, 모든 스트림 작업의 완료 플래그를 확인한 후 최종 출력

#### 한줄 요약
- 고정 메모리 확보와 스트림 동기화라는 관리 비용을 지불하는 대가로, 직렬로 드러나던 호스트-디바이스 전송 지연을 다른 스트림의 커널 실행 뒤로 숨긴다.

## Ⅴ. 종류 및 비교

| 병렬 프로그래밍 모델 | CUDA (NVIDIA) | SYCL / oneAPI (Intel/이종) | OpenCL (Khronos) |
|:---|:---|:---|:---|
| 적용 기준 | 극대화된 AI 성능과 풍부한 라이브러리 생태계 요구 시 | 벤더 비종속 단일 모던 C++ 코드베이스 유지 시 | 임베디드 및 이종 벤더 하드웨어 저수준 직접 제어 시 |
| 핵심 특징 | **C/C++ 확장 문법** 및 cuDNN/TensorRT 최적화 | 모던 C++17 기반 표준 싱글 소스 및 **이기종 다중 타깃** | C99 기반 저수준 API 및 **런타임 JIT 컴파일** |
| 한계 | NVIDIA 하드웨어 독점 **벤더 종속성(Lock-in)** | 하드웨어 벤더별 런타임 성능 편차 존재 | 장황한 초기화 보일러플레이트 코드 및 개발 복잡도 |

#### 한줄 요약
- 범용 이종 플랫폼에는 SYCL/OpenCL이 쓰이나, 최첨단 AI 및 고성능 컴퓨팅(HPC) 영역에서는 CUDA가 독보적 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **고정 메모리(Pinned/Page-Locked Memory)**: OS 페이징에 의해 스왑 아웃되지 않도록 물리 메모리에 상주시켜 DMA가 즉시 고속 접근할 수 있는 호스트 메모리.
- **커널 퓨전(Kernel Fusion)**: 연속된 여러 개의 소규모 커널을 하나의 커널로 결합하여 글로벌 메모리 읽기/쓰기를 온칩 레지스터/공유 메모리로 대체하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| PCIe 버스 대역폭 한계로 인한 호스트-디바이스 전송 병목 | **고정 메모리(Pinned)** 및 다중 스트림 비동기 파이프라이닝 | 데이터 전송 지연시간 100% 은닉 및 GPU 유휴 제거 |
| 소규모 커널 연속 호출에 따른 드라이버 런칭 오버헤드 | **커널 퓨전(Kernel Fusion)** 및 CUDA Graphs 적용 | 드라이버 런칭 오버헤드 대폭 절감 및 처리량 극대화 |
| 글로벌 메모리 비연속 접근으로 인한 메모리 대역폭 낭비 | 공유 메모리 **타일링(Tiling)** 및 SoA 변환 적용 | **메모리 병합** 달성 및 DRAM 트랜잭션 절감 |

#### 한줄 요약
- 실무에서는 고정 메모리와 다중 스트림으로 전송 지연을 은닉하고, 커널 퓨전과 공유 메모리 타일링으로 연산 효율을 극대화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CUDA Graphs**: 일련의 커널 실행 및 메모리 복사 작업들을 실행 그래프(DAG)로 사전에 정의하여 CPU의 개별 드라이버 런칭 오버헤드를 원천 제거하는 기술.
- **Triton(OpenAI Triton)**: 복잡한 CUDA C++ 프로그래밍 없이 파이썬 코드로 블록 수준 병렬 커널을 작성하여 최적의 GPU 머신 코드를 생성하는 최신 컴파일러 언어.

</details>

직관적인 계층형 병렬 추상화와 풍부한 라이브러리 생태계를 결합하여 AI 및 고성능 컴퓨팅의 글로벌 표준으로 자리매김한 플랫폼이며, CUDA Graphs 및 Triton 언어와의 융합을 통한 연산 파이프라인 최적화 진화.

#### 한줄 요약
- CUDA는 GPGPU 병렬 컴퓨팅의 글로벌 표준이며, 공유 메모리 타일링과 비동기 스트림 중첩을 통해 GPU 잠재력을 100% 실현한다.
