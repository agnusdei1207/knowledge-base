## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **쿠다(Compute Unified Device Architecture)**: 엔비디아 그래픽 처리 장치의 숨겨진 병렬 연산 코어들을 그래픽이 아닌 범용 컴퓨팅에 직접 뜯어고쳐 부려먹을 수 있도록 길을 열어준 C/C++ 기반의 강력한 병렬 소프트웨어 생태계이다.
- **호스트(Host)**: 칩 밖에서 큰 그림을 그리고 쿠다 커널을 세팅하여 장치(GPU)에 일을 던져주고 제어하는 중앙 처리 장치(CPU) 사령관이다.
- **장치(Device)**: 호스트가 던져준 어마어마한 양의 데이터를 수천 개의 코어로 잘게 쪼개어 빛의 속도로 갈아버리는 그래픽 처리 장치(GPU) 노가다 부대이다.

</details>

- 정의: **호스트**가 그래픽 처리 장치 **장치**의 스레드 계층과 메모리를 제어하여 커널 병렬성을 극대화하는 **쿠다** 프레임워크
- 배경: 중앙 처리 장치의 직렬 실행 방식이 지닌 대규모 텐서 병렬 연산 처리 대역폭의 물리적 한계를 극복하기 위함

#### 한줄 요약

- 그래픽만 그리던 GPU를 해킹하다시피 열어젖혀, 수천 개의 코어에 데이터를 밀어 넣고 C 코드로 직접 통제하며 무지막지한 병렬 연산을 뽑아내는 엔비디아의 절대 권력 플랫폼이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **커널(Kernel)**: GPU의 수많은 스레드들이 각자 자기 데이터를 들고 똑같이 읊어대며 실행해야 하는 병렬 구동 전용 함수(명령어 세트)이다.
- **그리드(Grid)**: 한 번의 커널 호출로 우르르 쏟아져 나온, 스레드 블록 수천 개를 한데 묶은 최상위 껍데기 군단이다.
- **블록(Block)**: 한 지붕(스트리밍 멀티프로세서) 아래에 옹기종기 모여서 칩 내부의 공유 메모리를 맘대로 털어 쓸 수 있는 수백 명의 스레드 집합이다.
- **스레드(Thread)**: 칩 내부에서 가장 밑바닥에 위치하며 실질적으로 더하기 빼기 연산을 쳐내는 최하위 일개미 단위이다.
- **병합 접근(Coalesced Access)**: 일개미들이 각자 메모리를 찔끔찔끔 퍼 오지 않고, 32명이 한 줄로 서서 거대한 한 덩어리로 메모리를 퍼 오게 만들어 대역폭을 쥐어짜는 기술이다.
- **스트림(Stream)**: 장치에 던져줄 데이터 복사 명령과 연산 커널들을 한 줄로 세워둔 비동기 대기열(큐)이다.
- **스트림 중첩(Stream Overlapping)**: A 대기열이 데이터를 복사하는 동안 멍때리지 않고, B 대기열의 연산을 겹쳐서 돌려버려 빈틈없이 칩을 혹사시키는 꼼수 기술이다.

</details>

- 깐깐한 제어 로직은 호스트(CPU)가 맡고, 무식한 대규모 연산은 장치(GPU)가 전담하는 명확한 **호스트 및 장치 분리** 아키텍처를 채택함.
- 수백만 개의 데이터를 한 번에 밀어버리기 위해 **그리드, 블록, 스레드**라는 3단계 계층적 병렬 작업 매핑 구조를 통해 텐서 연산을 산산조각 내어 분산함.
- 메모리를 퍼 올 때의 끔찍한 병목을 줄이는 **병합 접근** 및, 연산과 메모리 복사를 야바위처럼 겹쳐버리는 **스트림 중첩**을 완벽히 지원함.

#### 한줄 요약

- CPU는 지휘만 하고 GPU는 연산만 하도록 나누며, 일을 수백만 스레드로 쪼개고, 겹치고 뭉쳐서 메모리 병목을 뚫어내는 지독한 최적화의 산물이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 런타임(Host Runtime)**: 그래픽 카드에 메모리를 잡고 데이터를 쏘아주며, 커널 스위치를 켜는 등 모든 더러운 뒷바라지를 도맡아 하는 호스트(CPU) 쪽의 소프트웨어 계층이다.
- **커널 실행 계층(Kernel Execution Hierarchy)**: 그리드를 블록으로 쪼개서 스트리밍 멀티프로세서(SM)에 쑤셔 넣고, 그 안에서 스레드들을 마구잡이로 뛰게 만드는 하드웨어 디스패치 구조이다.
- **장치 메모리 계층(Device Memory Hierarchy)**: 레지스터(주머니), 공유 메모리(사물함), 전역 메모리(대형 창고)로 나뉘어 속도와 용량에 따라 데이터를 철저히 계급화한 GPU 저장 체계이다.
- **스트리밍 멀티프로세서(Streaming Multiprocessor)**: 스레드 블록 수십 개를 집어삼키고 그 안에서 단일 명령 다중 스레드(SIMT)로 연산을 미친 듯이 갈아버리는 GPU 내부의 거대한 물리적 코어 섬이다.

</details>

```text
[ 쿠다 소프트웨어 및 하드웨어 계층적 제어 프레임워크 ]
       [ 호스트 중앙 처리 장치 ]              [ 장치 그래픽 처리 장치 ]
                   │                                     │
      [ 호스트 런타임 및 API 계층 ]                      │
                   │ (명령 하달)                         │
                   ▼                                     ▼
           [ 쿠다 비동기 스트림 ] ──(제어)──> [ 커널 실행 하드웨어 계층 ]
                                                         │
                                                         ▼
                                             [ 장치 계층적 메모리 구조 ]
```

| 구성요소 | 책임 |
|:---|:---|
| **호스트 런타임** | 장치 메모리 공간 할당, 데이터 입출력 전송 제어 및 GPU **커널** 함수 실행 런칭의 총괄 관리 |
| **쿠다** **스트림** | 명령어 비동기 대기열 큐잉 및 수많은 커널 연산의 실행 순서와 꼬여있는 의존성 철저 제어 |
| **커널 실행 계층** | **스트리밍 멀티프로세서** 물리 코어 상에 **그리드** 및 **블록** 단위의 스레드 병렬 우겨넣기 배치 |
| **장치 메모리 계층** | 극초고속 레지스터, **공유 메모리**, 느려터진 전역 메모리를 통한 계층적 텐서 데이터 피딩 공급 |

#### 한줄 요약

- CPU 쪽 런타임이 큐(스트림)에 일거리를 차곡차곡 밀어 넣으면, GPU의 실행 계층이 이를 낚아채 계층화된 메모리에서 밥을 퍼 먹으며 연산을 쳐낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **복사 엔진(Copy Engine)**: 연산 코어가 더하기 빼기를 하느라 바쁠 때, 옆에서 몰래 호스트와 장치 간 데이터를 펌프질해 나르는 별도의 전담 하드웨어 엔진이다.
- **호스트 대 장치(Host-to-Device)**: 컴퓨터 메인 메모리(RAM)에 있는 데이터를 좁아터진 PCIe 버스를 타고 그래픽 카드 메모리(VRAM)로 밀어 넣는 눈물 나는 전송 방향이다.
- **장치 대 호스트(Device-to-Host)**: 그래픽 카드가 연산을 끝내고 만든 결과물을 다시 컴퓨터 메인 메모리로 토해내는 전송 방향이다.
- **이벤트(Event)**: 비동기로 막무가내로 돌아가는 스트림들 사이에서 "여기까진 꼭 끝내고 다음 거 해라"라고 말뚝을 박아주는 소프트웨어 래치 동기화 신호이다.

</details>

```text
[ 쿠다 비동기 스트림 큐잉 및 커널 파이프라인 실행 제어 흐름 ]
                               │
                               ▼
        [ 1. 쿠다 스트림 생성 및 복잡한 얽힘 방지용 이벤트 의존성 등록 ]
                               │
                               ▼
     [ 2. 복사 엔진을 통한 비동기 호스트 대 장치(H2D) 데이터 펌핑 쑤셔넣기 ]
                               │
                               ▼
     [ 3. 장치 커널 실행 계층에 블록 디스패치 및 무자비한 병렬 연산 쳐내기 ]
                               │
                               ▼
         [ 4. 커널 폭파 완료 후 이벤트 래치 트리거 및 대기 중인 후속 작업 승인 ]
                               │
                               ▼
       [ 5. 복사 엔진을 통한 비동기 장치 대 호스트(D2H) 연산 결과물 반환 토해내기 ]
```

### 동작 원리

1. 스트림 및 의존성 등록: **쿠다** 스트림 대기열을 생성하고, 스트림이 꼬이지 않도록 **이벤트** 기반의 동기화 실행 말뚝(순서)을 철저히 설정함.
2. 비동기 입력 복사: **복사 엔진**을 맹렬히 가동하여 호스트의 메인 데이터를 장치(GPU) 창고로 **비동기 호스트 대 장치** 방식으로 밀어 넣음.
3. 커널 파이프라인 실행: 칩 내부 **커널 실행 계층**에 그리드와 블록 파라미터를 던져주어, 스레드들이 깨어나 병렬 연산을 미친 듯이 시작함.
4. 완료 이벤트 대기: 커널 연산이 끝남과 동시에 **이벤트** 래치를 찰칵하고 트리거하여 묶여 있던 후속 작업들의 목줄을 풀어 승인함.
5. 비동기 결과 복사: 다 구워진 연산 결과 텐서를 **비동기 장치 대 호스트** 전송으로 좁은 버스를 지나 호스트 메모리에 최종 반환함.

#### 한줄 요약

- 스트림 대기열을 만들고, 비동기로 데이터를 밀어 넣은 뒤, 커널을 돌려 갈아버리고, 이벤트로 눈치를 보다가 잽싸게 결과를 빼오는 물 흐르는 파이프라인이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사이클(SYCL)**: 엔비디아의 쿠다 독재에 반발하여, AMD든 인텔이든 가리지 않고 C++ 코드 한 줄로 다 돌려버리겠다고 만든 크로스 플랫폼 오픈 표준 껍데기이다.
- **엔디 레인지(N-Dimensional Range)**: 사이클(SYCL)에서 쿠다의 그리드와 블록 개념을 훔쳐 와 이름만 바꾼, N차원의 거대한 작업 배치 공간 정의 모델이다.
- **중앙 처리 장치 멀티스레딩(CPU Multithreading)**: 수천 개의 멍청한 스레드가 아니라 수십 개의 엄청나게 똑똑한 코어에 복잡하고 큰 덩어리 작업을 던져 병렬로 처리하는 고전적인 기법이다.

</details>

| 비교 항목 | **쿠다** | **사이클** | **중앙 처리 장치 멀티스레딩** |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 오직 엔비디아 하드웨어에 종속되어 영혼까지 쥐어짜는 극한 최적화 달성 시 | 엔비디아, 인텔, AMD 등 이종 가속기 간의 하드웨어 눈치 안 보는 이식성 확보 시 | 복잡하게 꼬인 조건 제어 흐름 및 소규모 덩어리 병렬 작업 처리 시 |
| 아키텍처 핵심 특징 | **그리드, 블록, 스레드** 매핑이라는 강력하고 하드웨어 밀착된 병렬성 통제 | **엔디 레인지** 기반의 우아하고 단일 소스인 오픈 표준 병렬 프로그래밍 모델 | 멀티 코어 기반으로 운영체제가 직접 관리하는 태스크 중심 직렬 처리 병렬화 |
| 극복해야 할 태생적 한계 | 엔비디아가 아니면 쳐다보지도 못하는 특정 벤더 생태계에 대한 강력한 노예 종속성 발생 | 표준을 맞추려다 보니 벤더 전용 밀착 최적화 쿠다 대비 피할 수 없는 미세 성능 손실 발생 | 턱없이 모자란 물리적 스레드 개수 및 코어 간 좁은 대역폭 병목 한계 |

#### 한줄 요약

- 속도와 생태계의 절대 갑을 원하면 CUDA, 여러 회사 칩을 다 써야 하면 SYCL, 복잡한 로직이면 CPU 멀티스레딩을 택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **전역 동기화(Global Synchronization)**: "다 끝날 때까지 모두 정지!"를 외치는 함수(`cudaDeviceSynchronize()`) 남발로, 잘 달리고 있던 수많은 스트림을 급브레이크 밟게 만드는 최악의 짓이다.
- **고정 호스트 메모리(Pinned Host Memory)**: 메인 메모리(RAM)가 가상 페이징으로 하드디스크로 쫓겨나지 않게 대못을 박아버려, GPU가 묻지도 따지지도 않고 빛의 속도로 데이터를 펌핑할 수 있게 만든 특별한 메모리 영역이다.
- **점유율(Occupancy)**: 칩 안의 텅 빈 연산 유닛 공간에 내가 짠 스레드 워프를 얼마나 꽉꽉 욱여넣었는지를 보여주는, 쿠다 최적화의 척도이다.
- **연산 집약도(Arithmetic Intensity)**: 데이터를 한 바이트 퍼 왔으면 연산을 몇 번이나 혹사시킬 수 있는지 나타내는 비율로, 이 값이 낮으면 연산기는 놀고 메모리만 불타는 지옥을 맛본다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 급브레이크인 무식한 **전역 동기화** 함수 남발로 인한 스트림 실행 마비 및 심각한 전송 병목 | **이벤트** 기반 비동기 래치를 짜 맞춰 스트림 간의 섬세한 의존성 최적화 구조망 구축 | 복사 연산과 커널 연산의 야바위 동시 겹침 처리로 칩 내 지연 은닉의 극대화 달성 |
| 호스트와 장치 간 좁아터진 PCIe 버스를 넘나드는 구역질 나는 메모리 복사 지연 오버헤드 | **고정 호스트 메모리** 할당 및 여러 개의 **스트림 중첩** 기법을 통한 복사 통신 우회 가림 적용 | 칩 내부 직접 메모리 접근 전송 속도를 100% 한계까지 끌어올리고 대기시간 완벽 은닉 |

| 느려터진 전역 메모리를 들락거리다 대역폭이 포화되어 수천 개 코어가 놀고먹는 성능 추락 참사 | 온칩 캐시인 공유 메모리를 극한으로 쥐어짜는 타일링 적용 및 텐서 **연산 집약도** 강제 조작 제어 | 바깥 전역 메모리로 나가는 통신 오버헤드 원천 단축 및 코어 **점유율** 100% 폭주 향상 |

#### 한줄 요약

- 동기화를 이벤트로 쪼개고, 고정 메모리로 복사 속도를 높이며, 공유 메모리 타일링으로 연산 집약도를 미친 듯이 올려야 진정한 쿠다 마스터가 된다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **병렬 플랫폼 선택 기준(Parallel Platform Selection Criteria)**: 어차피 엔비디아 노예가 될 거라면 쿠다를 쓰고, 굳이 이종 가속기의 자유를 원한다면 성능 손해를 감수하고 사이클(SYCL)을 쓴다는 냉혹한 하드웨어 종속성 판단 잣대이다.

</details>

- **병렬 플랫폼 선택 기준**에 따라 특정 벤더 하드웨어의 영혼을 쥐어짜는 **세부 최적화** 절대 필요 시 **쿠다**, 이종 가속기 간의 범용 **이식성** 확보 시 **사이클** 적용을 단호히 결정함

#### 한줄 요약

- 엔비디아 칩의 한계를 120% 뚫어버리려면 노예 종속을 각오하고 CUDA를 맹신해야 하며, 그것이 싫다면 성능을 포기하고 SYCL을 쥐어야 한다.
