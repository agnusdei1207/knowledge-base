## 미리 알고가기

- **통합 컴퓨팅 장치 구조(Compute Unified Device Architecture, CUDA)**: NVIDIA GPU에서 병렬 연산을 구현하는 플랫폼이자 프로그래밍 모델
- **호스트(Host)**: CUDA 작업을 제출하는 CPU 측 실행 환경
- **장치(Device)**: CUDA 커널과 메모리를 실행하는 GPU
- **커널(Kernel)**: GPU의 여러 스레드가 병렬 실행하는 함수
- **실행 계층(Grid, Block, Thread)**: 전체 작업·협력 묶음·개별 실행 단위
- **스트림(Stream)**: 작업을 등록 순서로 처리하는 장치 대기열
- **고정 호스트 메모리(Pinned Host Memory)**: 비동기 호스트 전송을 위한 페이지 고정 메모리
- **공유 메모리(Shared Memory)**: 블록 스레드가 재사용하는 온칩 메모리
- **이벤트(Event)**: 스트림 간 의존성과 완료를 표시하는 동기화 객체
- **중앙 처리 장치(Central Processing Unit, CPU)**: CUDA 작업을 준비·제출하고 결과를 처리하는 호스트 프로세서
- **그래픽 처리 장치(Graphics Processing Unit, GPU)**: 다수 스레드로 CUDA 커널을 병렬 실행하는 장치 프로세서
- **단일 명령 다중 스레드(Single Instruction, Multiple Threads, SIMT)**: 하나의 명령어를 워프의 활성 스레드에 공통 발행하는 GPU 실행 모델
- **스트리밍 멀티프로세서(Streaming Multiprocessor, SM)**: 스레드 블록을 배치하고 워프를 실행하는 GPU 연산 단위
- **연산 집약도(Arithmetic Intensity)**: 이동한 데이터 양에 비해 수행한 연산량의 비율
- **병합 접근(Coalesced Access)**: 인접 스레드의 메모리 요청을 적은 전송으로 합치는 접근
- **SYCL**: 여러 제조사의 가속기를 표준 C++ 코드로 제어하는 크로노스 그룹의 이식형 병렬 프로그래밍 모델
- **다차원 실행 범위(N-Dimensional Range, ND-range)**: SYCL에서 전체 작업 항목과 작업 그룹의 다차원 배치를 나타내는 실행 범위
- **통합 공유 메모리(Unified Shared Memory, USM)**: 호스트와 장치가 같은 포인터 주소로 접근하도록 메모리를 관리하는 SYCL 기능
- **불균일 메모리 접근(Non-Uniform Memory Access, NUMA)**: 프로세서와 메모리의 물리적 위치에 따라 접근 시간이 달라지는 구조
- **호스트→장치·장치→호스트 복사(Host-to-Device·Device-to-Host, H2D·D2H)**: CPU 메모리에서 GPU 메모리로 입력을 보내는 전송과 계산 결과를 반대로 가져오는 전송
- **복사 엔진(Copy Engine)**: GPU 연산 코어와 별도로 호스트·장치 메모리 사이의 DMA 전송을 수행하는 하드웨어

## Ⅰ. 개요

- 정의/개념: NVIDIA GPU의 **커널·스레드 병렬 실행** 플랫폼
- 기존 한계: CPU 순차 실행은 **대규모 데이터 병렬 처리량**에 한계

### 쉽게 이해하기 (학습용)

- CPU가 작업표를 만들면 GPU의 여러 작업조가 일을 나눠 처리한다

## Ⅱ. 특징

- **호스트·장치 분리**로 작업 제출과 커널 실행 구분
- **그리드·블록·스레드** 계층으로 병렬 작업 구성
- **병합 접근·스트림 중첩**이 데이터 이동 비용 절감

### 쉽게 이해하기 (학습용)

- 작업조 크기를 맞추고 조건이 되면 운반과 계산을 겹쳐 진행한다

## Ⅲ. 아키텍처 및 구성요소

### 도표안 A. CUDA 실행 정적 구조

```mermaid
flowchart LR
    H["호스트 런타임"] --> S["CUDA 스트림"]
    S --> K["커널 실행 계층"]
    S <--> M["장치 메모리 계층"]
    K <--> M
```

| 설계 요소 | 입력·상태 | 역할 |
|:---|:---|:---|
| 호스트 런타임 | 작업·메모리·완료 상태 | 할당·복사·실행·동기화 관리 |
| CUDA 스트림 | 복사·커널·이벤트 | 등록 순서와 의존성 관리 |
| 커널 실행 계층 | 그리드·블록·스레드 | 병렬 작업 배치 |
| 장치 메모리 계층 | 레지스터·공유·전역 데이터 | 범위별 데이터 저장·공급 |

> 요약: 런타임이 스트림을 통해 실행 계층과 메모리를 제어한다

### 도표안 B. CUDA 스트림 복사·커널·완료 시퀀스

```mermaid
sequenceDiagram
    participant H as 호스트 애플리케이션
    participant R as CUDA 런타임
    participant S as CUDA 스트림
    participant C as 복사 엔진
    participant M as 장치 메모리
    participant K as SM·커널 실행 계층

    H->>R: ① H2D·커널·D2H·이벤트 제출
    R->>S: ② 의존 순서대로 작업 등록
    S->>C: ③ 비동기 H2D 복사 시작
    C->>M: ④ 입력 데이터를 장치 메모리에 기록
    S->>K: ⑤ H2D 완료 후 커널 실행
    loop 그리드의 스레드 블록
        K->>M: ⑥ 입력·공유 타일 데이터 접근
        M-->>K: ⑦ 데이터·저장 완료 반환
    end
    K-->>S: ⑧ 커널 완료 상태 전달
    S->>C: ⑨ 비동기 D2H 복사 시작
    C->>M: ⑩ 결과 데이터 읽기 요청
    M-->>C: ⑪ 결과 데이터 반환
    C-->>H: ⑫ 고정 호스트 메모리에 결과 기록
    S-->>H: ⑬ 이벤트 완료 통지
```

### 동작 원리

1. **① H2D·커널·D2H·이벤트 제출**: 호스트 애플리케이션은 입력 복사, 커널 실행, 결과 복사와 완료 이벤트를 CUDA 런타임에 비동기로 제출한다.
2. **② 의존 순서대로 작업 등록**: 런타임은 같은 스트림 안에서 H2D→커널→D2H→이벤트 순서가 보장되도록 명령을 등록한다.
3. **③ 비동기 H2D 복사 시작**: 스트림의 선행 조건이 충족되면 복사 엔진이 고정 호스트 메모리에서 입력 전송을 시작한다.
4. **④ 입력 데이터를 장치 메모리에 기록**: 복사 엔진은 CPU의 데이터 복사 없이 입력을 GPU 전역 메모리에 기록한다.
5. **⑤ H2D 완료 후 커널 실행**: 스트림은 입력 복사가 끝난 뒤 커널의 그리드와 블록을 사용 가능한 SM에 배치한다.
6. **⑥ 입력·공유 타일 데이터 접근**: 각 스레드 블록은 전역 메모리에서 타일을 읽고 공유 메모리에서 재사용하며 병렬 연산을 수행한다.
7. **⑦ 데이터·저장 완료 반환**: 장치 메모리는 읽기 데이터를 커널에 제공하고 결과 쓰기의 완료 상태를 반환한다.
8. **⑧ 커널 완료 상태 전달**: 그리드의 모든 블록이 끝나면 실행 계층은 스트림의 다음 명령이 진행할 수 있도록 완료를 알린다.
9. **⑨ 비동기 D2H 복사 시작**: 스트림은 커널 결과를 호스트로 가져오도록 복사 엔진에 지시한다.
10. **⑩ 결과 데이터 읽기 요청**: 복사 엔진은 장치 메모리의 출력 버퍼를 DMA로 읽는다.
11. **⑪ 결과 데이터 반환**: 장치 메모리는 출력 데이터를 복사 엔진에 전달한다.
12. **⑫ 고정 호스트 메모리에 결과 기록**: 복사 엔진은 반환 데이터를 페이지 고정된 호스트 버퍼에 기록한다.
13. **⑬ 이벤트 완료 통지**: D2H 복사가 끝나면 스트림 이벤트가 완료되고 호스트는 결과를 안전하게 사용한다.

### 쉽게 이해하기 (학습용)

- 관리자·일정표·작업조·저장 공간이 실행과 자료 이동을 나눠 맡는다

## Ⅳ. 종류 및 비교

| 병렬 프로그래밍 방식 | CUDA | SYCL | CPU 멀티스레딩 |
|:---|:---|:---|:---|
| 적용 기준 | NVIDIA **세부 최적화** | 다중 제조사 **이식성** | 복잡한 분기·**작은 작업** |
| 핵심 특징 | **그리드·블록·스레드** | **ND-range·작업 그룹** | 독립 **스레드·태스크** |
| 한계 | 공급자 종속·**전송 병목** | 구현별 **성능 편차** | 제한된 **병렬 처리량** |

> 요약: NVIDIA 최적화는 CUDA, 이식성은 SYCL이 적합하다

### 쉽게 이해하기 (학습용)

- 전용 공장 최적화는 CUDA, 여러 공장 이동은 SYCL이 알맞다

## Ⅴ. 실무 고려사항 및 대응 방안

| 운영 위험 | 대응 | 기대 효과 |
|:---|:---|:---|
| 전역 동기화가 복사·커널 중첩을 차단 | 스트림·이벤트로 실제 의존성만 표현 | 동시 실행 확대 |
| 호스트–장치 전송이 연산 시간을 초과 | 고정 메모리·비동기 복사·배치와 데이터 상주 적용 | 전송 비용 절감 |
| 비동기 커널 오류가 뒤늦게 발견 | 실행 직후 오류 확인과 경계별 동기화·로그 적용 | 원인 위치 식별 |
| 블록 크기·레지스터·공유 메모리 불균형 | 프로파일러로 점유율·대역폭·연산 집약도 공동 탐색 | 병목별 자원 조정 |

> 행렬 곱은 입력을 공유 메모리 크기의 타일로 나누고 블록 안의 여러 스레드가 같은 값을 반복 사용해 전역 메모리 전송을 줄인다.

### 쉽게 이해하기 (학습용)

- 일정표의 앞일이 끝나면 작업조를 가동하고 결과를 돌려받는다.
- 재료를 작업대 크기로 나눠 같은 조가 반복 사용한다

## Ⅵ. 결론

- GPU 가속을 위해 전송·동기화를 검토하여 **CUDA** 활용

### 쉽게 이해하기 (학습용)

- 전용 공장을 채울 일감이 많고 이동비를 줄일 수 있을 때 CUDA를 쓴다
