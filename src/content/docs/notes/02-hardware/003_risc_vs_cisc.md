## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 프로세서가 실행 가능한 기계어 명령어, 레지스터 집합, 주소 지정 방식을 정의한 규격.
- **축소 명령어 집합(RISC, Reduced Instruction Set Computer)**: 고정 길이의 단순한 기계어를 사용하여 파이프라인 처리에 최적화한 프로세서.
- **복합 명령어 집합(CISC, Complex Instruction Set Computer)**: 가변 길이 명령어로 단일 명령을 통해 복합 연산을 수행하고 코드 밀도를 높인 프로세서.

</details>

- 정의/개념: 명령어 길이와 인코딩 복잡도에 따라 단순 고정 길이 축소형(RISC)과 가변 길이 복합형(CISC)으로 분류하는 명령어 집합 구조(ISA)
- 배경/필요성: 메모리 절약을 위한 가변 길이 CISC의 디코더 병목을 극복하고 **단순 고정 길이 및 단일 사이클 파이프라인 고속화 실현**

#### 한줄 요약

- RISC는 **단순 고정 명령 파이프라인**, CISC는 **가변 복합 명령 코드 밀도**에 집중

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로드•스토어 구조(Load/Store Architecture)**: 연산은 레지스터 내에서만 수행하고 메모리 접근은 전용 로드/스토어 명령어로만 한정한 아키텍처.
- **코드 밀도(Code Density)**: 일정 크기의 메모리 공간에 수용 가능한 프로그램 기능 단위의 집약도.

</details>

- 규칙적 고정 길이 포맷을 통한 **명령어 경계 판정 간소화 및 디코더 지연 최소화**
- **로드•스토어 구조** 강제를 통한 메모리 접근 주기와 데이터 연산 주기의 완전 분리
- 가변 길이 및 복합 메모리 연산을 통한 **코드 밀도 극대화 및 소프트웨어 하위 호환성 유지**

#### 한줄 요약

- RISC는 **로드·스토어 기반 전력 효율**, CISC는 **복합 명령 기반 코드 밀도** 확보

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **마이크로연산($\mu\text{op}$)**: 복잡한 CISC 기계어를 프로세서 실행 유닛이 직접 처리할 수 있도록 잘게 쪼갠 단순 내부 연산 단위.
- **하드와이어드 디코더**: 논리 회로로 직접 명령어를 해독하여 1클록 내에 제어 신호를 생성하는 초고속 디코더.

</details>

```text
[ 구조 체계 ]
 ├─ 명령어 인코딩 ──> 고정 길이(32bit) vs 가변 길이(1~15Byte)
 └─ 피연산자 모델 ──> 로드•스토어(RISC) vs 레지스터•메모리(CISC)

[ 백엔드 회로 ]
 ├─ 해독•변환부 ──> 직접 하드와이어드 제어 vs 마이크로코드(μop) 변환
 └─ 실행 유닛   ──> 슈퍼스칼라 파이프라인 실행
```

선의 의미: 명령어 인코딩과 피연산자 모델이 디코더 회로 및 파이프라인 실행 유닛으로 연결되는 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 명령어 인코딩 | **명령어 인코딩**에 따른 비트 배치 |
| 피연산자 모델 | 명령어의 물리적 **피연산자 모델** 규정 |
| 해독•변환부 | 기계어를 내부 **마이크로연산**이나 제어 신호로 파싱 |
| 실행 유닛 | 최종 **실행 유닛**이 산술 및 논리 연산 처리 |

#### 한줄 요약

- RISC의 **하드와이어드 디코더**와 CISC의 **마이크로옵($\mu\text{op}$) 변환부** 비교

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 경계 판정(Instruction Boundary Detection)**: 가변 길이 바이트 스트림에서 각 명령어의 시작점과 끝점을 계산하는 전처리.

</details>

```text
[ PC 주소 인출 (Fetch) ]
         │
         ▼
[ 경계 판정 및 해독 (Decode) ]
  ├─ 고정 인코딩 (RISC) ──> 단일 주기 하드와이어드 직접 해독
  └─ 가변 파싱 (CISC)   ──> 명령어 경계 판정 후 마이크로연산(μop) 분해
         │
         ▼
[ 피연산자 읽기 및 연산 실행 (Execute) ]
         │
         ▼
[ 아키텍처 상태 갱신 (Write-Back) ]
```

**동작 원리**

1. **명령어 인출**: 프로그램 카운터(PC)가 지정하는 메모리 주소에서 기계어 바이트 스트림 인출
2. **경계 판정 및 해독**: 고정 길이는 1주기 내 직접 해독하며, 가변 길이는 경계 판정 후 $\mu\text{op}$ 시퀀스로 분해
3. **피연산자 읽기 및 연산**: 레지스터 파일 또는 로드된 메모리 피연산자를 바탕으로 파이프라인 연산 수행
4. **결과 기록**: 연산 결과를 목표 레지스터에 기록하고 상태 플래그 갱신

#### 한줄 요약

- 고정 길이는 **직접 단일 주기 해독**, 가변 길이는 **$\mu\text{op}$ 분해 변환** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **$\mu\text{op}$ 캐시**: CISC 디코더가 이미 변환한 마이크로연산을 저장하여 반복 루프 실행 시 디코딩 단계를 우회하는 캐시.

</details>

| 비교 항목 | 축소 명령어 집합 (RISC) | 복합 명령어 집합 (CISC) |
|:---|:---|:---|
| 적용 기준 | 모바일, 임베디드, 고성능 클라우드 (ARM, RISC-V) | 레거시 호환성 중심 PC, 엔터프라이즈 서버 (x86) |
| 핵심 특징 | 고정 길이(32bit), 로드·스토어 구조, 단순 하드와이어드 | 가변 길이(1~15B), 메모리 직접 연산, 마이크로코드 |
| 한계 및 위험 | 낮은 코드 밀도로 인한 메모리/캐시 점유율 증가 | 복잡한 프런트엔드 디코더 면적 및 전력 소비 증가 |

#### 한줄 요약

- RISC는 **파이프라인 최적화**, CISC는 **방대한 바이너리 호환성** 강점

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **압축 명령어(Compressed Instructions)**: RISC-V 'C' 확장이나 ARM Thumb처럼 16비트 명령을 혼용하여 코드 밀도를 높이는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 길이 판정으로 인한 디코더 병목 | 디코딩 결과를 저장하는 **마이크로연산 캐시**와 명령 정렬 유닛 탑재 | 반복 루프 시 **해독 처리량** 대폭 증대 |
| 고정 길이에 따른 코드 크기 증가 | 16비트 **압축 명령어** 도입 | I-Cache 적중률 개선 및 밴드위스 절약 |
| 기존 레가시 애플리케이션의 호환성 부재 | JIT 기반 **호환 계층** 도입 | 아키텍처 전환 시 소프트웨어 재개발 비용 최소화 |

#### 한줄 요약

- **$\mu\text{op}$ 캐시·압축 명령·바이너리 변환**으로 단점 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **현대 프로세서의 융합**: CISC 프로세서도 내부 백엔드는 RISC와 동일한 $\mu\text{op}$ 실행 엔진을 채택하는 마이크로아키텍처 융합 추세.

</details>

- 워크로드 특성 기반 **전력 효율(RISC) vs 바이너리 호환성(CISC) 아키텍처 선택**

#### 한줄 요약

- **전력 효율·코드 밀도·생태계 호환성** 축으로 최적 ISA 결정
