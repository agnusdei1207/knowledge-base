## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 하드웨어가 소프트웨어에 제공하는 인터페이스 규격으로, 기계어 명령어 형식, 범용 레지스터 집합, 메모리 주소 지정 방식 등을 정의한 컴퓨터 아키텍처 명세.
- **축소 명령어 집합 컴퓨터(Reduced Instruction Set Computer, RISC)**: 규칙적인 명령어 형식과 로드·스토어 구조로 파이프라인 구현을 단순화한 프로세서 구조.
- **복합 명령어 집합 컴퓨터(Complex Instruction Set Computer, CISC)**: 가변 길이와 복합 연산 명령어를 지원하여 단일 명령어로 복합 작업을 수행하고 코드 밀도를 높인 프로세서 구조.

</details>

- 정의/개념: 명령어의 길이·형식과 주소 지정 방식을 단순화하여 파이프라인 효율을 우선할지, 또는 복합화하여 코드 밀도를 우선할지에 따라 분기하는 **명령어 집합 구조(ISA)** 설계 패러다임
- 배경/필요성: 하드웨어 복잡도 완화와 파이프라인 고속화 요구(**RISC**)와 메모리 절감 및 바이너리 코드 밀도 극대화 요구(**CISC**)의 상충으로 설계 패러다임 분기

#### 한줄 요약
- RISC는 단순한 고정 명령어 조합으로 파이프라인 속도를 극대화하고, CISC는 복합 명령어로 프로그램 코드 크기를 줄인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로드/스토어 구조(Load/Store Architecture)**: 메모리 참조를 전용 로드(Load)와 스토어(Store) 명령어에만 허용하고, 모든 산술·논리 연산은 레지스터 간에만 수행하도록 강제하는 아키텍처.
- **코드 밀도(Code Density)**: 동일한 소프트웨어 기능을 구현할 때 기계어 바이너리가 차지하는 바이트 용량의 압축 효율성.
- **가변 길이 명령어(Variable-Length Instruction)**: 명령어의 종류와 피연산자 수에 따라 명령어 비트 길이가 1바이트에서 수십 바이트까지 동적으로 달라지는 형식.

</details>

- RISC: 규칙적인 명령어 형식과 **로드/스토어 구조**로 디코딩·파이프라인 제어 단순화
- RISC: 규칙적인 명령어 형식 덕분에 디코더 회로가 단순하여 파이프라인 효율 및 고클록 달성에 유리
- CISC: 단일 명령어로 메모리 참조와 산술 연산을 동시 수행하는 복합 명령어를 지원하여 높은 **코드 밀도** 확보
- CISC: **가변 길이 명령어** 체계로 인해 하드웨어 디코더가 복잡하며, 현대 x86은 내부에서 RISC형 마이크로 연산($\mu$-op)으로 변환해 실행

#### 한줄 요약
- RISC는 실행 단계를 일정하게 만들어 하드웨어를 가볍게 하고, CISC는 풍부한 명령어로 메모리 대역폭을 절감하며 내부적으로 마이크로 연산 변환을 통해 성능을 절충한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **마이크로 연산 변환기($\mu$-op Decoder)**: CISC 프로세서의 프론트엔드에 탑재되어 복잡한 가변 길이 x86 명령어를 고정 길이의 단순한 RISC형 마이크로 연산들로 쪼개어 백엔드 실행 엔진에 공급하는 하드웨어 유닛.
- **레지스터 파일(Register File)**: 다수의 고속 범용 레지스터를 집적하여 다중 읽기/쓰기 포트를 제공하는 하드웨어 저장 블록.

</details>

```text
[ISA 실행 계층 구조]
  │
  ├─ [RISC 아키텍처]
  │     ├─ [고정 포맷] (32비트 단순 인코딩)
  │     ├─ [디코더 회로] (하드와이어드 고속 해석)
  │     ├─ [레지스터 파일] (대용량 범용 레지스터)
  │     └─ [메모리 접근] (순수 Load/Store 엔진)
  │
  └─ [CISC 아키텍처]
        ├─ [가변 포맷] (1~15바이트 복합 인코딩)
        ├─ [디코더 회로] (μ-op 변환기 및 ROM)
        ├─ [레지스터 파일] (특수 목적 중심 적은 수)
        └─ [메모리 접근] (직접 메모리 피연산자)
```

선의 의미: RISC와 CISC의 하드웨어 실행 계층 및 구성요소 소속 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 명령어 포맷 | RISC 고정 길이와 CISC **가변 길이** 인코딩 규정 |
| 디코더 회로 | 기계어를 제어 신호로 해석하거나 **마이크로 연산 변환기**로 μ-op 변환 |
| **레지스터 파일** | 연산 피연산자와 결과의 고속 보관 |
| 메모리 접근 엔진 | RISC 로드·스토어와 CISC 메모리 피연산자 처리 |

#### 한줄 요약
- 현대 컴퓨터 구조는 외부 ISA 인터페이스(RISC/CISC)와 내부 실행 엔진(하드와이어드/$\mu$-op 디코더)이 분리되어 상호 장점을 융합하는 방향으로 수렴했다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마이크로코드(Microcode)**: 복잡한 복합 명령어를 여러 단계의 단순 기본 동작으로 나누어 실행하기 위해 제어 메모리(Control ROM)에 저장된 하위 레벨 제어 프로그램.

</details>

```text
1. 명령어 인출 (Fetch) ── 메모리에서 명령어 비트열 버퍼 적재
    │
    ▼
2. 아키텍처별 디코딩 방식 판정
   ┌───────────────────┴───────────────────┐
[ RISC 디코딩 ]                          [ CISC 디코딩 ]
    │                                       │
    ├─ 규칙적 형식의 하드와이어드 해석     ├─ 가변 길이 명령어 경계 판별
    │                                       ▼
    │                                     μ-op 디코더 변환 (단순/복합)
    └───────────────────┬───────────────────┘
                        │
                        ▼
3. 파이프라인 실행 (Execute) ── RISC 레지스터 연산 / CISC μ-op 비순서 실행
                        │
                        ▼
4. 결과 기록 (Write-Back) 및 상태 갱신
```

분기 결과: **RISC**는 규칙적 디코딩, **CISC**는 명령어 경계 판별·μ-op 변환 또는 **마이크로코드** 실행

#### 한줄 요약
- RISC는 규칙적 형식으로 해석하고, CISC는 마이크로 연산으로 변환해 실행 엔진에 전달한다.

## Ⅴ. 종류 및 비교

| 명령어 집합 구조 | RISC (축소 명령어 집합) | CISC (복합 명령어 집합) |
|:---|:---|:---|
| 적용 기준 | 모바일, 임베디드, 고효율 서버 (ARM, RISC-V) | PC, 레거시 서버, 고성능 범용 컴퓨팅 (x86) |
| 핵심 특징 | 고정 길이 명령어 및 **로드/스토어** 구조 | **가변 길이** 명령어 및 높은 **코드 밀도** |
| 한계 | 프로그램 바이너리 크기 및 메모리 대역폭 요구 증가 | 복잡한 디코더 회로로 인한 칩 면적 및 전력 소모 증가 |
| 명령어당 클록(CPI) | 목표 CPI $\approx$ 1 (단일 사이클 실행 지향) | 가변 CPI (명령어 복잡도에 따라 수 클록 소요) |
| 컴파일러 역할 | 명령어 조합·레지스터 할당 최적화 | 가변 길이 명령어 선택·스케줄링 최적화 |

#### 한줄 요약
- 단순한 회로와 고효율 파이프라이닝이 필요하면 RISC, 높은 코드 밀도와 하위 바이너리 호환성이 필수적이면 CISC가 선택 기준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **압축 명령어 세트(Compressed Instructions)**: 자주 쓰이는 명령어를 16비트 등 단축 형식으로 인코딩하여 바이너리 크기를 줄이는 기법(ARM Thumb, RISC-V 'C' 확장).
- **마이크로 연산 융합(Micro-op Fusion)**: 인접한 2개 이상의 마이크로 연산을 단일 실행 유닛에서 한 번에 처리하도록 병합하여 파이프라인 대역폭을 절감하는 x86 최적화 기법.
- **μ-op 캐시(Micro-op Cache)**: 디코더가 이미 변환한 마이크로 연산 열을 저장해 두고 같은 코드가 재실행될 때 가변 길이 디코딩 단계를 건너뛰어 마이크로 연산을 곧바로 백엔드에 공급하는 프론트엔드 캐시.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| RISC 코드 크기 증가로 I-Cache 미스 확대 | **압축 명령어** 적용 | 코드 밀도 향상으로 캐시 미스 감소 |
| CISC 가변 디코딩으로 인한 프론트엔드 전력 및 지연 증가 | **μ-op 캐시** 탑재 | 디코더 단계 바이패스 및 프론트엔드 전력 절감 |
| CISC의 복합 $\mu$-op 다량 생성으로 인한 백엔드 파이프라인 병목 | **마이크로 연산 융합** 기술 적용 | 파이프라인 대역폭 절감 및 실행 효율 향상 |

#### 한줄 요약
- RISC는 압축 명령어로 코드 크기 한계를 보완하고, CISC는 디코딩된 $\mu$-op 캐시와 융합 기술로 프론트엔드 복잡도 한계를 극복한다.

## Ⅶ. 결론

- 현대 프로세서는 프론트엔드에서 CISC를 $\mu$-op으로 분해하고 백엔드는 RISC 파이프라인으로 처리하는 상호 융합 구조가 정착되었으며, 최근 AI·클라우드·에지 환경에서는 전력 대 성능비가 우수한 ARM 및 오픈소스 RISC-V 중심의 확장 가속화 추세

#### 한줄 요약
- 현대 프로세서는 RISC의 간결한 실행 효율과 CISC의 높은 코드 밀도를 상호 수용하여 융합된 고성능 아키텍처로 진화했다.
