## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 프로세서가 실행 가능한 기계어 명령어, 레지스터 집합, 주소 지정 방식 등을 정의한 하드웨어 소프트웨어 인터페이스이다.
- **축소 명령어 집합 컴퓨터(Reduced Instruction Set Computer, RISC)**: 고정 길이의 단순한 기계어를 사용하여 명령어 해독 속도를 높이고 파이프라인 처리에 최적화한 프로세서이다.
- **복합 명령어 집합 컴퓨터(Complex Instruction Set Computer, CISC)**: 다양한 형태의 가변 길이 명령어로 단일 명령을 통해 복잡한 연산을 수행하고 코드 밀도를 높인 프로세서이다.
- **해독 처리량(Decode Throughput)**: 디코더 유닛이 단일 클록 주기에 파이프라인 백엔드로 전달할 수 있는 기계어 및 마이크로 연산의 수이다.

</details>

- 정의: 명령어의 길이와 복잡도에 따라 고정 길이 축소형과 가변 길이 복합형으로 분류하는 **명령어 집합 아키텍처** 규격
- 배경: 제한된 메모리 한계를 극복하기 위한 복합형 설계가 파이프라인 병목을 유발함에 따라 고속 해독을 위한 축소형이 등장함

#### 한줄 요약

- 축소 명령어 집합 컴퓨터는 고정 길이 명령으로 해독 지연을 최소화하며, 복합 명령어 집합 컴퓨터는 복잡한 가변 길이 명령으로 높은 코드 밀도를 달성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로드•스토어 구조(Load/Store Architecture)**: 연산은 범용 레지스터 내에서만 수행하고 메모리 접근은 명시적 로드/스토어 명령만 허용하는 구조이다.
- **코드 밀도(Code Density)**: 일정 바이트 크기의 메모리 공간에 수용 가능한 프로그램 기능 단위 및 기계어 명령어의 집약도이다.
- **마이크로아키텍처(Microarchitecture)**: 동일한 명령어 집합을 만족시키는 프로세서 칩 내부의 디코더 및 실행 유닛의 구체적 물리 회로이다.

</details>

- **축소 명령어 집합 컴퓨터**의 규칙적인 포맷을 통해 명령어 경계 판정 회로를 간소화하고 디코더 지연을 최소화함.
- **복합 명령어 집합 컴퓨터**의 가변 길이 및 복합 메모리 연산을 통해 단일 기계어로 다중 작업을 구현하여 **코드 밀도**를 극대화함.
- **축소 명령어 집합 컴퓨터**는 **로드•스토어 구조**를 강제하여 메모리 접근과 데이터 연산 주기를 완전히 격리함.
- 동일 아키텍처라도 현대 프로세서는 **마이크로아키텍처** 기법에 따라 파이프라인 효율과 전력 효율이 결정됨.

#### 한줄 요약

- 축소 명령어 집합 컴퓨터는 로드 스토어 기반으로 디코더를 단순화하고, 복합 명령어 집합 컴퓨터는 가변 길이 연산으로 코드 밀도를 높인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인코딩(Instruction Encoding)**: 연산자 필드와 레지스터 번호, 즉치 값을 명령어 비트 열에 배치하는 규격이다.
- **마이크로연산(Micro-operation, $\mu\text{op}$)**: 복잡한 기계어를 프로세서 실행 유닛이 직접 처리할 수 있도록 분해한 단순 내부 연산 단위이다.
- **피연산자 모델(Operand Model)**: 명령어가 참조하는 오퍼랜드의 레지스터 할당 방식 및 메모리 연산 허용 여부이다.
- **해독•변환부(Decode Unit)**: 기계어 비트열을 파싱하여 내부 데이터 경로를 구동하는 제어 신호로 전환하는 블록이다.
- **실행 유닛(Execution Unit)**: 해독된 연산자 신호에 따라 산술, 논리 판단을 병렬 처리하는 파이프라인 연산기이다.

</details>

```text
[ 구조 체계 ]
 ├─ 명령어 인코딩 ──> 고정 길이 vs 가변 길이
 └─ 피연산자 모델 ──> 로드•스토어 vs 레지스터•메모리

[ 백엔드 회로 ]
 ├─ 해독•변환부 ──> 직접 제어 신호 vs 마이크로연산 변환
 └─ 실행 유닛   ──> 파이프라인 실행
```

| 구성요소 | 책임 |
|:---|:---|
| 명령어 인코딩 | **명령어 인코딩**에 따른 비트 배치 |
| 피연산자 모델 | 명령어의 물리적 **피연산자 모델** 규정 |
| 해독•변환부 | 기계어를 내부 **마이크로연산**이나 제어 신호로 파싱 |
| 실행 유닛 | 최종 **실행 유닛**이 산술 및 논리 연산 처리 |

#### 한줄 요약

- 하드와이어드 디코더 중심의 직접 제어 방식과 마이크로코드 롬을 통한 디코딩 구조로 나뉜다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 경계 판정(Instruction Boundary Detection)**: 연속 적재된 스트림에서 각 명령어의 시작과 끝 길이를 산출하는 전처리이다.
- **아키텍처 상태(Architectural State)**: 레지스터, PC, 플래그 등 소프트웨어가 관찰 가능한 논리적 상태이다.
- **명령어 인출(Instruction Fetch)**: 명령어 주소에서 기계어 데이터를 인출하는 단계이다.
- **경계 판정•해독(Boundary Detect & Decode)**: 기계어를 분석하여 제어 신호나 시퀀스를 생성하는 단계이다.
- **피연산자 읽기•연산 실행(Operand Fetch & Execute)**: 레지스터 파일에서 값을 읽거나 주소를 계산하여 연산하는 단계이다.
- **아키텍처 상태 갱신(State Update)**: 계산 결과를 지정된 레지스터나 메모리에 반영하는 단계이다.

</details>

```text
[ PC 주소 인출 ]
        │
        ▼
[ 경계 판정 및 해독 ]
  ├─ 고정 인코딩 ──> 단일 주기 하드와이어드 해독
  └─ 가변 파싱   ──> 마이크로코드 분해 변환
        │
        ▼
[ 피연산자 읽기 및 연산 ]
        │
        ▼
[ 아키텍처 상태 갱신 ]
```

### 동작 원리

1. 명령어 인출: 프로그램 카운터가 지정하는 기계어 코드를 메모리에서 인출함.
2. 경계 판정•해독: 고정 길이는 1주기 내에 직접 해독을 완결하고, 가변 길이는 **명령어 경계 판정**을 거쳐 **마이크로연산**으로 분해함.
3. 피연산자 읽기•연산 실행: 지정된 레지스터 혹은 로드된 메모리 피연산자를 바탕으로 병렬 연산을 진행함.
4. 아키텍처 상태 갱신: 레지스터와 상태 비트에 연산 결과를 기록하여 **아키텍처 상태**를 확정함.

#### 한줄 요약

- 인출 후 고정 길이 명령어는 직접 해독하고 가변 길이 명령어는 마이크로연산으로 분해하여 연산을 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **바이너리 호환성(Binary Compatibility)**: 작성된 기계어 바이너리를 별도 재컴파일 없이 최신 CPU에서 구동 가능한 성질이다.
- **해독부 면적(Decoder Area)**: 프로세서 칩에서 디코더 회로가 차지하는 면적 비율이다.
- **명령 수(Instruction Count)**: 동일 알고리즘 수행 시 요구되는 총 기계어 명령어의 수이다.
- **규칙적 형식(Fixed-Length Format)**: 명령어의 길이가 32비트 등으로 고정되어 파싱 비용이 없는 포맷이다.
- **가변 형식(Variable-Length Format)**: 명령어 길이가 다양하여 하드웨어 파싱이 복잡한 포맷이다.
- **프런트엔드 복잡도(Frontend Complexity)**: 명령어 인출과 경계 판정을 담당하는 입구부의 회로 집적도이다.
- **코드 크기(Code Size)**: 디스크 및 메모리에 적재되는 프로그램의 물리적 용량이다.

</details>

| 비교 항목 | 축소 명령어 집합 컴퓨터 | 복합 명령어 집합 컴퓨터 |
|:---|:---|:---|
| 대표 ISA | ARM, RISC-V | x86 |
| 명령어 형식 | **규칙적 형식** | **가변 형식** |
| 메모리 접근 | 메모리와 연산 분리 구조 | 메모리 직접 연산 허용 |
| 디코더 특성 | 적은 **해독부 면적** | 높은 **프런트엔드 복잡도** |
| 밀도 및 수량 | 낮은 밀도와 많은 **명령 수** | 높은 밀도와 작은 **코드 크기** |
| 특장점 | 파이프라인 고속화 및 전력 효율 | 방대한 소프트웨어 **바이너리 호환성** |

#### 한줄 요약

- 축소 명령어 집합 컴퓨터는 전력 효율성을 극대화하고, 복합 명령어 집합 컴퓨터는 코드 밀도 및 호환성을 유지한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **압축 명령어(Compressed Instruction)**: 자주 쓰는 명령을 축소하여 밀도를 끌어올리는 기술이다.
- **호환 계층(Compatibility Layer)**: 이종 아키텍처 간 바이너리를 변환하는 소프트웨어 번역 모듈이다.
- **명령 정렬(Instruction Alignment)**: 가변 명령어 경계가 정렬되지 않을 때 하드웨어 인출 효율을 보정하는 기법이다.
- **마이크로연산 캐시($\mu\text{op}$ Cache)**: 변환된 스트림을 저장해 루프 실행 시 디코딩 단계를 우회하는 초고속 캐시이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 길이 판정으로 인한 디코더 병목 | 디코딩 결과를 저장하는 **마이크로연산 캐시**와 **명령 정렬** 유닛 탑재 | 반복 루프 시 **해독 처리량** 대폭 증대 |
| 고정 길이에 따른 코드 크기 증가 | 16비트 **압축 명령어** 도입 | I-Cache 적중률 개선 및 밴드위스 절약 |
| 기존 레가시 애플리케이션의 호환성 부재 | JIT 기반 **호환 계층** 도입 | 아키텍처 전환 시 소프트웨어 재개발 비용 최소화 |

#### 한줄 요약

- 마이크로연산 캐시 탑재, 압축 명령어 적용, 호환 계층 도입을 통해 성능 병목과 호환성 문제를 동시에 해결한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **마이크로아키텍처 벤치마크(Microarchitecture Benchmark)**: 워크로드에서의 클록당 성능과 전력 효율을 평가하는 정밀 측정이다.
- **아키텍처 선택 기준(Architecture Selection Criteria)**: 시스템 목적에 따라 최적의 명령 집합을 결정하는 평가 지표이다.

</details>

- 시스템 목적에 맞는 **아키텍처 선택 기준**과 체계적인 **마이크로아키텍처 벤치마크**를 통해 결정

#### 한줄 요약

- 전력, 호환성, 성능 등 시스템의 목표 지표에 맞추어 프로세서 아키텍처를 선택해야 한다.
