## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 소프트웨어에 보이는 명령어, 레지스터, 주소 지정 규칙의 인터페이스입니다.
- **축소 명령어 집합 컴퓨터(Reduced Instruction Set Computer, RISC)**: 단순하고 규칙적인 명령어 형식을 중심으로 설계한 ISA 계열입니다.
- **복합 명령어 집합 컴퓨터(Complex Instruction Set Computer, CISC)**: 다양한 형식과 복합 기능의 명령어를 제공하는 ISA 계열입니다.

</details>

- 정의/개념: 명령어의 길이·형식과 주소 지정 방식을 단순화할지 또는 복합화할지에 따라 분기하는 **명령어 집합 구조(ISA) 설계 패러다임**
- 배경/필요성: 단일 고정 설계로는 **디코딩 복잡도·파이프라인 효율·코드 밀도 간 상충 해결 불가**

#### 한줄 요약

- RISC와 CISC는 같은 프로그램 기능을 단순한 명령어 조합으로 풀지, 한 명령어에 더 많이 담을지의 선택입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로드/스토어 구조(Load/Store Architecture)**: 메모리 접근을 로드와 스토어 명령어에만 두고 연산은 레지스터에서 수행하는 구조입니다.
- **코드 밀도(Code Density)**: 같은 기능을 표현하는 데 필요한 명령어 바이트 수의 저장 효율입니다.
- **가변 길이 명령어(Variable-Length Instruction)**: 명령어마다 비트 또는 바이트 길이가 달라지는 형식입니다.

</details>

- RISC: 규칙적 명령어 형식과 **로드/스토어 구조**
- RISC: 단순 해석 경로에 유리한 **파이프라인 구성**
- CISC: 복합 연산과 **가변 길이 명령어**
- CISC: 한 기능당 바이트 수를 줄이는 **코드 밀도**

#### 한줄 요약

- RISC는 실행 단계를 일정하게 만들고, CISC는 한 명령어가 표현하는 일을 늘려 코드 크기를 줄입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **연산 코드(Operation Code, Opcode)**: 명령어가 수행할 연산의 종류를 지정하는 비트 필드입니다.
- **피연산자(Operand)**: 연산의 입력값, 결과 위치, 주소를 지정하는 정보입니다.
- **명령어 디코더(Instruction Decoder)**: 명령어 비트열을 실행에 필요한 제어 신호로 해석하는 회로입니다.

</details>

```text
[ISA 계약]
├─ 명령어 형식
│  ├─ Opcode
│  └─ 피연산자
├─ 레지스터 모델
├─ 주소 지정 방식
└─ 명령어 디코더
```

| 구성요소 | 책임 |
|:---|:---|
| 명령어 형식 | Opcode와 피연산자 비트 배치 규정 |
| 레지스터 모델 | 프로그램에 보이는 저장 위치 규정 |
| 주소 지정 방식 | 피연산자 위치를 찾는 규칙 제공 |
| 명령어 디코더 | 명령어 형식의 실행 제어 신호 변환 |

#### 한줄 요약

- ISA는 명령어를 어떻게 쓰고 데이터를 어디서 찾으며 하드웨어가 어떻게 해석할지를 약속합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터입니다.
- **마이크로 연산(Micro-operation)**: 하나의 기계어 명령어를 실행하기 위해 내부에서 수행하는 세부 동작입니다.

</details>

```text
[ 1. 명령어 인출 ]
        │
        ▼
[ 2. 형식 해석 ]
        │
        ▼
[ 3. 피연산자 접근 ]
        │
        ▼
[ 4. 연산 및 상태 갱신 ]
```

**동작 원리**

1. **명령어 인출**: PC 위치의 명령어 비트열 확보
2. **형식 해석**: Opcode와 피연산자 필드 판독
3. **피연산자 접근**: RISC는 로드/스토어, CISC는 형식별 접근 수행
4. **연산 및 상태 갱신**: 결과와 다음 PC를 프로그램 상태에 반영

#### 한줄 요약

- RISC는 형식 해석을 단순하게 하고, CISC는 가변 길이와 복합 기능을 해석한 뒤 실행합니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RISC(축소 명령어 집합)**: 고정 길이 명령어와 로드/스토어 구조로 파이프라이닝 효율을 극대화한 구조.
- **CISC(복합 명령어 집합)**: 가변 길이 복합 명령어로 높은 코드 밀도와 하위 호환성을 제공하는 구조.

</details>

| ISA 계열 | RISC | CISC |
|:---|:---|:---|
| 적용 기준 | 규칙적 실행과 구현 단순성 | 코드 밀도와 기존 바이너리 호환성 |
| 핵심 특징 | 고정 형식과 레지스터 중심 연산 | 복합 명령어와 다양한 주소 지정 |
| 한계 | 명령어 수와 코드 크기 증가 가능성 | 디코더와 실행 제어 복잡도 증가 |

#### 한줄 요약

- 일정한 실행 경로가 중요하면 RISC, 코드 크기와 호환성이 중요하면 CISC가 유리한 방향입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache)**: 반복 인출되는 명령어를 CPU 가까이에 보관하는 캐시입니다.
- **명령어 압축(Compressed Instruction)**: 자주 쓰는 명령어를 짧은 형식으로 표현해 코드 크기를 줄이는 방식입니다.
- **이진 변환(Binary Translation)**: 한 ISA용 기계어를 다른 ISA에서 실행할 형태로 바꾸는 기법입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| RISC 코드 증가로 명령어 인출 부담 | 명령어 압축과 명령어 캐시 적용 | 저장 공간과 인출 지연 완화 |
| CISC 해석 경로가 길어 전단 지연 증가 | 빈번한 형식의 디코딩 경로 최적화 | 명령어 해석 지연 감소 |
| ISA 교체로 기존 바이너리 실행 불가 | 이진 변환과 호환성 시험 적용 | 이식 범위와 전환 위험 관리 |

#### 한줄 요약

- RISC는 인출 부담을, CISC는 해석 부담을 다루며 ISA 전환에는 호환성 검증이 필요합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **이진 호환성(Binary Compatibility)**: 기존 기계어 프로그램을 수정 없이 같은 환경에서 실행할 수 있는 성질입니다.

</details>

- 단순·고효율은 **RISC**, 코드 밀도·바이너리 호환은 **CISC** 선택

#### 한줄 요약

- ISA는 명령어 하나의 복잡도만이 아니라, 실행 효율과 프로그램 자산을 어느 쪽에 더 둘지로 결정합니다.
