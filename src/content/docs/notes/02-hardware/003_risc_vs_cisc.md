## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 소프트웨어에 공개된 명령어•레지스터•주소 지정 규격이다.
- **축소 명령어 집합 컴퓨터(Reduced Instruction Set Computer, RISC)**: 단순하고 규칙적인 명령어 중심의 ISA 설계 방식이다.
- **복합 명령어 집합 컴퓨터(Complex Instruction Set Computer, CISC)**: 복합 기능 명령어 중심의 ISA 설계 방식이다.
- **설계 절충**: 해독 비용•코드 밀도•호환성 사이의 균형을 정하는 판단이다.
- **해독 처리량**: 해독부가 한 클록 주기에 내부 연산으로 변환할 수 있는 명령어 수이다.

</details>

- 정의/개념: 명령어 복잡도, 길이 규칙, 메모리 접근 방식에 따라 축소형과 복합형으로 대립되는 **명령어 집합 아키텍처(ISA) 설계 방식**이다.
- 배경/필요성: 복합 가변 길이 명령어 체계에서는 해독 회로가 복잡해져 파이프라인 단계를 고속화하고 병렬 처리를 확장하는 데 한계가 있다.

#### 한줄 요약

- RISC는 고정 길이 명령어와 로드·스토어 구조로 파이프라인 지연을 최소화하고, CISC는 가변 길이 명령어와 다양한 메모리 연산으로 코드 밀도를 높인다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **로드·스토어 구조**: 메모리 접근을 로드·스토어 명령으로 제한하고 나머지 연산을 레지스터 사이에서 수행하는 구조이다.
- **코드 밀도**: 일정한 메모리 공간에 담을 수 있는 프로그램 명령의 양이다.
- **마이크로아키텍처**: ISA를 해독부·실행 유닛·캐시 등의 회로로 구현한 내부 구조이다.

</details>

- **RISC**의 규칙적 명령 형식으로 경계 판정·해독 회로 단순화가 핵심이다.
- **CISC**의 복합·가변 길이 명령으로 명령당 기능과 코드 밀도 증가한다.
- **RISC**는 **로드·스토어 구조**로 메모리 접근과 레지스터 연산을 분리한다.
- 같은 ISA도 **마이크로아키텍처**에 따라 처리량·전력 특성 변화가 핵심이다.

#### 한줄 요약

- 동일한 ISA라도 파이프라인 깊이, 비순차 실행 엔진 등 마이크로아키텍처 구현 방식에 따라 명령당 주파수(CPI)와 전력 소비 특성이 달라진다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **명령어 인코딩**: 연산 종류와 피연산자를 명령 비트의 길이·필드 위치로 표현하는 규칙이다.
- **마이크로연산**: 복합 ISA 명령을 프로세서 내부에서 실행하도록 나눈 단순 연산 단위이다.
- **피연산자 모델**: 명령어가 사용할 수 있는 레지스터·메모리 값과 접근 방식을 정한 규칙이다.
- **해독·변환부**: 명령 비트를 실행 가능한 제어 신호나 내부 연산으로 바꾸는 회로이다.
- **실행 유닛**: 해독된 연산을 수행하고 결과를 레지스터나 메모리에 기록하는 회로이다.

</details>

```text
ISA 구현 구조
├─ 명령 표현
│  ├─ 명령어 인코딩
│  └─ 피연산자 모델
└─ 구현 회로
   ├─ 해독·변환부
   └─ 실행 유닛
```

가지의 의미: ISA 명령 표현과 구현 회로의 정적 책임 구분이다.

| 구성요소 | 책임 |
|:---|:---|
| 명령어 인코딩 | 명령 길이와 필드 위치 정의 |
| 피연산자 모델 | 허용 피연산자와 접근 방식 정의 |
| 해독·변환부 | 명령 비트를 제어 신호나 **마이크로연산**으로 변환 |
| 실행 유닛 | 해독된 연산 실행과 결과 기록 |

#### 한줄 요약
- ISA가 명령 형식과 피연산자 접근을 정하고, 해독부와 실행 유닛이 이를 연산으로 구현한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **명령어 경계 판정**: 메모리의 명령 바이트에서 각 명령어의 시작 위치와 길이를 구분하는 처리이다.
- **아키텍처 상태**: ISA가 소프트웨어에 공개한 레지스터·메모리·상태값이다.
- **명령어 인출**: 프로그램 카운터가 가리키는 주소에서 명령 바이트를 읽는 단계이다.
- **경계 판정•해독**: 명령어의 시작•길이•필드를 구분해 제어 신호나 내부 연산을 만드는 단계이다.
- **피연산자 읽기•연산 실행**: 지정된 레지스터•메모리 값을 읽어 실행 유닛에서 연산하는 단계이다.
- **아키텍처 상태 갱신**: 연산 결과를 ISA가 공개한 레지스터•메모리•상태값에 반영하는 단계이다.

</details>

```text
명령어 주소
    │
    ▼
1. 명령어 인출
    │
    ▼
2. 경계 판정·해독
    ├─ RISC: 규칙적 명령을 제어 신호로 변환
    └─ CISC: 가변 길이 명령을 내부 연산으로 분해
    │
    ▼
3. 피연산자 읽기·연산 실행
    │
    ▼
4. 아키텍처 상태 갱신
```

### 동작 원리

1. **명령어 인출**: 프로그램 카운터가 가리키는 명령 바이트를 확보한다.
2. **경계 판정•해독**: **명령어 경계 판정**으로 길이와 필드를 구분해 실행 동작을 생성한다.
3. **피연산자 읽기·연산 실행**: 지정된 레지스터·메모리 값을 연산에 사용한다.
4. **아키텍처 상태 갱신**: 연산 결과를 ISA가 정의한 상태에 반영한다.

#### 한줄 요약

- RISC는 Direct Hardware Control Signal Mapping, CISC는 Instruction Pre-decoding 및 $\mu \text{op}$ (Micro-op) Decomposition 후 Execution Unit으로 전달한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **바이너리 호환성**: 기존 실행 파일을 다시 컴파일하지 않고 같은 ISA에서 실행할 수 있는 성질이다.
- **해독부 면적**: 명령 해독 회로가 반도체 칩에서 차지하는 물리적 공간이다.
- **명령 수**: 같은 작업을 수행하는 데 필요한 명령어 개수이다.
- **전력**: 프로세서가 단위 시간에 소비하는 전기 에너지이다.
- **x86 바이너리**: x86 ISA 명령으로 컴파일된 실행 파일이다.
- **규칙적 형식**: 명령 길이와 필드 위치가 일정해 경계를 쉽게 판정할 수 있는 인코딩 형식이다.
- **가변 형식**: 명령마다 길이와 필드 구성이 달라 경계 판정이 필요한 인코딩 형식이다.
- **프런트엔드 복잡도**: 명령어 인출•경계 판정•해독•변환 회로의 구조와 처리 부담이다.
- **코드 크기**: 프로그램의 기계 명령이 메모리에서 차지하는 용량이다.

</details>

| ISA 설계 | RISC | CISC |
|:---|:---|:---|
| 적용 기준 | 재컴파일 가능하고 **해독부 면적**이 제한된 경우 | **바이너리 호환성**과 기존 **x86 바이너리** 실행이 필요한 경우 |
| 핵심 특징 | **규칙적 형식**·로드·스토어 구조 | **가변 형식**·메모리 피연산자 허용 |
| 한계 | 동일 작업의 **명령 수**•**코드 크기** 증가 가능 | 경계 판정•변환에 따른 **프런트엔드 복잡도** |

> 요약: 규칙적 해독은 RISC, x86 호환은 CISC가 핵심이며 **전력**은 구현별로 측정한다.

#### 한줄 요약

- RISC는 Simple Decoder Array 기반 파이프라인 최적화, CISC는 Complex Microcode ROM/Decoder 및 $\mu \text{op}$ Fusion으로 Instruction Stream을 구동한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **압축 명령어**: 자주 사용하는 연산을 짧게 인코딩하여 코드 크기와 명령 캐시 사용량을 줄이는 명령어이다.
- **에뮬레이션**: 다른 ISA의 동작을 소프트웨어로 모사하는 방식이다.
- **호환 계층**: 기존 실행 환경의 요청을 새 플랫폼 규약으로 연결하는 계층이다.
- **명령 정렬**: 가변 길이 명령의 시작 경계를 찾아 해독기에 맞춰 배치하는 처리이다.
- **명령 캐시 미스**: 필요한 명령어를 캐시에서 찾지 못해 하위 메모리에서 가져오는 상황이다.
- **마이크로아키텍처 벤치마크**: 구현에서 처리시간•전력•자원 사용량을 측정하는 시험이다.
- **마이크로연산 캐시**: 해독한 내부 연산을 저장해 반복 실행 때 재해독을 줄이는 캐시이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **가변 형식**의 경계 판정으로 해독부 포화 | **마이크로연산 캐시**•**명령 정렬** 최적화 | **해독 처리량** 증가 |
| RISC의 명령 수 증가로 **명령 캐시 미스** 확대 | **압축 명령어**•코드 배치 최적화 | 코드 크기와 인출 미스 감소 |
| ISA 전환으로 기존 바이너리 실행 불가 | 재컴파일 또는 **에뮬레이션**•**호환 계층** 제공 | **바이너리 호환성** 유지 |
| ISA 이름만으로 성능•전력 오판 | **마이크로아키텍처 벤치마크** 수행 | 구현별 처리량•전력 비교 근거 확보 |

#### 한줄 요약

- 명령 인출•해독 처리량, 코드 밀도, 내부 연산 수와 실행 백엔드 사용률을 함께 측정해야 ISA 설계의 영향을 판단할 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **벤치마크**: 동일한 작업의 처리 시간•전력•자원 사용량을 측정하여 ISA와 마이크로아키텍처 조합을 비교하는 시험이다.
- **ISA 선택 기준**: 해독 단순성•바이너리 호환성•실측 성능으로 ISA 설계를 평가하는 기준이다.

</details>

- **ISA 선택 기준**에 따라 단순 해독은 **RISC**, x86 호환은 **CISC**를 우선하되 최종 선택은 **벤치마크**로 검증한다.

#### 한줄 요약

- Binary Compatibility, Code Density Requirement, Frontend Decode Power Consumption 및 Real-world Workload Benchmark(SPECint, SPECfp)를 다각적 평가한다.
