## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **단일 명령 다중 데이터(Single Instruction Multiple Data)**: 뇌(제어)는 하나인데 입(연산기)이 100개 달려 있어서, 한 번의 명령으로 100개의 데이터를 융단폭격하듯 한꺼번에 씹어버리는 극한의 효율 통제 방식이다.
- **다중 명령 다중 데이터(Multiple Instruction Multiple Data)**: 뇌도 여러 개, 입도 여러 개라 각자 알아서 자기 할 일을 남 눈치 안 보고 비동기적으로 처리하는 자유분방한 각자도생의 처리 방식이다.
- **병렬 아키텍처(Parallel Architecture)**: 똑같은 일을 무식하게 밀어붙이는 데이터 병렬성과, 서로 다른 일을 똑똑하게 나눠서 하는 작업 병렬성의 장점만 쏙쏙 빼먹기 위해 칩 구조를 영혼까지 뜯어고친 설계 체계이다.

</details>

- 정의: 멀티 코어 간 **다중 명령 다중 데이터**(MIMD) 작업 병렬성과, 코어 내부 **단일 명령 다중 데이터**(SIMD) 벡터 레인의 무식한 데이터 병렬성을 복합 결합하는 하이브리드 **병렬 아키텍처**
- 배경: SIMD의 치명적인 조건문(if-else) 붕괴 약점과, MIMD가 똑같은 데이터를 처리할 때 뇌(제어 유닛)를 낭비하는 디코딩 오버헤드 참사를 상호 보완할 완벽한 체계가 필요했기 때문

#### 한줄 요약

- 코어끼리는 각자 다른 일을 하고(MIMD), 코어 안에서는 똑같은 단순 노동을 수백 개씩 동시에 처리하게(SIMD) 만들어 효율의 끝을 보는 현대 칩 구조이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공통 명령(Common Instruction)**: 100개의 연산기에게 일일이 명령을 내리지 않고, 확성기로 딱 한 번 방송을 때려 일괄적으로 똑같은 동작을 강제하는 무자비한 지시이다.
- **독립 명령 흐름(Independent Instruction Flow)**: 남이 덧셈을 하든 말든 나는 뺄셈을 하겠다며, 각 코어가 오직 자신의 프로그램 카운터(PC)만 바라보고 독고다이로 달리는 파이프라인이다.
- **계층형 병렬성(Hierarchical Parallelism)**: 위층(코어 간)에서는 각자 다른 프로젝트를 지휘하고, 아래층(코어 내부)에서는 똑같은 벽돌 나르기를 수백 명이 동시에 수행하는 극단적 계층 분리 구조이다.

</details>

- 매번 명령을 해석하느라 버려지는 전기와 시간을 원천 차단하는 **공통 명령** 기반의 융단폭격 벡터 연산을 코어 내부에 강제 적용함.
- 각기 다른 웹 브라우저, 게임, 백그라운드 앱을 동시에 돌리기 위해 코어별 **독립 명령 흐름**을 완전히 분리 보유함.
- 코어 간 자유분방한 MIMD 구조와 코어 내부의 획일적인 SIMD 레인을 뼛속까지 일체화한 **계층형 병렬성** 하이브리드 아키텍처를 구성함.

#### 한줄 요약

- 코어 밖에서는 명령을 독립적으로 나눠서 처리하고, 코어 안에서는 확성기로 방송해 한 번에 수백 개의 연산기를 통제하는 이중인격 구조이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **작업 큐(Work Queue)**: 운영체제가 던져준 수백 개의 스레드 작업들이 각 코어의 부름을 받기 전까지 대기열에 묶여있는 통제 대기소이다.
- **연산 레인(Execution Lane)**: SIMD 확성기 명령을 받아들이면, 군인들이 열 맞춰 행진하듯 똑같은 곱셈을 100개의 레인에서 한 방에 끝내버리는 무식한 하드웨어 유닛이다.
- **배리어(Barrier)**: 코어들이 각자 미친 듯이 일하다가 "여기서 일단 다 모여라!" 하고 결승선에 줄을 세워, 가장 늦게 끝나는 놈이 올 때까지 기다리게 만드는 동기화 차단기이다.

</details>

```text
[ SIMD 및 MIMD 이중 결합 하이브리드 병렬 아키텍처 프레임워크 ]
                   [ 상위 응용 프로그램 및 쓰레드 뭉치 ]
                                   │
                           [ 독립 작업 큐 대기열 ]
                                   │
               [ MIMD 스케줄러 (누가 쉴지 일할지 감시하고 배분) ]
                  /                │                 \
+---------------▼---+ +----------▼--------+ +---------▼---------+
| 코어 1 (자유행동) | | 코어 2 (자유행동) | | 코어 N (자유행동) |
|   [ SIMD 레인 1 ] | |   [ SIMD 레인 1 ] | |   [ SIMD 레인 1 ] |
|   [ SIMD 레인 2 ] | |   [ SIMD 레인 2 ] | |   [ SIMD 레인 2 ] |
|   [ SIMD 레인 N ] | |   [ SIMD 레인 N ] | |   [ SIMD 레인 N ] |
+---------------+---+ +----------+--------+ +---------+---------+
                │                │                    │
                ▼                ▼                    ▼
      [ 공유 메모리 및 전역 동기화 배리어 (여기서 모여서 결과 취합) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 독립 **작업 큐** 대기열 | 다중 독립 스레드 단위 작업 패킷의 큐잉 대기 및 스케줄러로 던지기 전 멱살 통제 제어 |
| 엠아이엠디(MIMD) 스케줄러 | 놀고 있는 꿀 빠는 유휴 코어를 색출하고, 각기 다른 비동기 작업을 쉴 틈 없이 디스패칭 분배 수행 |
| 에스아이엠디(SIMD) 지원 코어군 | 코어 독립 실행 통제 및 그 내부 하드웨어 벡터 **연산 레인**의 무자비한 융단폭격 병렬 연산 수행 |
| 공유 메모리 및 동기화기 | 코어 간 계산 끝난 텐서 공유 및 가장 느린 놈을 기다리는 전역 **배리어** 동기화 래칭 철저 통제 |

#### 한줄 요약

- 스케줄러가 작업 큐에서 일을 빼서 코어(MIMD)들에게 나눠주면, 코어 안의 수백 개 레인(SIMD)이 그걸 씹어먹고 공유 메모리(배리어)에서 다시 만나는 시스템이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **작업 기술자(Work Descriptor)**: 스케줄러가 코어한테 "이 메모리 주소부터 저 주소까지 이 함수로 돌려라"라고 넘겨주는 청부 살인(계산) 계약서이다.
- **벡터 연산(Vector Operation)**: 숫자 하나하나(스칼라)를 쪼잔하게 계산하지 않고, 숫자 덩어리(벡터/텐서)를 뭉텅이로 썰어 한 방에 곱해버리는 통쾌한 연산이다.
- **동기화 완료(Synchronization Completion)**: 배리어에 마지막 꼴찌 코어까지 무사히 도착하여 텐서 퍼즐이 완벽히 맞춰지고, 다음 퀘스트로 넘어가는 기분 좋은 순간이다.

</details>

```text
[ 엠아이엠디 다중 코어 기반 에스아이엠디 혼합 작업 연산 흐름 ]
                               │
                               ▼
     [ 1. 스케줄러가 작업 큐에서 각기 다른 작업 기술자(일거리) 낚아채기 ]
                               │
                               ▼
        [ 2. 다중 코어들에게 서로 다른 일거리를 비동기로 마구잡이 투척 ]
                               │
            +---------------------------------------+
            | 각 코어 안의 획일적인 융단폭격 구간   |
            |   3. 텐서 벡터 연산 무자비하게 수행   |
            +---------------------------------------+
                               │
                               ▼
     [ 4. 뻘뻘 흘린 코어별 연산 완결 텐서를 전역 공유 메모리에 복사 및 취합 ]
                               │
                               ▼
     [ 5. 모든 코어가 모였는지 멱살 잡고 확인하는 배리어 동기화 해제 완료 ]
```

### 동작 원리

1. 독립 작업 스케줄링 인출: **작업 큐**로부터 각기 다른 특성을 가진 **작업 기술자**를 인출하고 스케줄링 발사 준비를 완료함.
2. 다중 코어 비동기 작업 배치: 스케줄러가 칩 안의 독립 코어들로 각기 다른 작업을 매정하게 할당하고 비동기 커널을 런칭시킴.
3. 텐서 벡터 연산 병렬 수행: 각 코어 내부에서 반복되는 지루한 데이터 패턴에 대해 내부 레인 기반 **벡터 연산**을 무자비하게 수행함.
4. 코어별 연산 결과 공유 이송: 연산 완결 텐서 조각을 코어 간 전역 공유 메모리로 냅다 이송하고 인덱스 퍼즐을 기록함.
5. 전역 동기화 배리어 해제: 모든 코어의 작업 완료를 확인하는 전역 **동기화 완료** 배리어 래치를 가차 없이 해제하고 다음 후속 작업을 연계함.

#### 한줄 요약

- 서로 다른 일을 코어들에게 던져주고(MIMD), 코어들은 자기 안의 수백 개 레인(SIMD)으로 박살을 낸 뒤, 배리어에 모여 결과물을 합치는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **조밀 텐서(Dense Tensor)**: 1만 곱하기 1만 크기의 행렬에 빈칸 하나 없이 숫자가 빼곡히 들어차 있어, 똑같은 덧셈을 수억 번 해야 하는 무식한 데이터 덩어리이다.
- **비정형 분기(Irregular Branch)**: 프로그램 코드에 조건문(if-else)이 떡칠되어 있어서, 똑같이 줄을 서 있던 연산기 중 절반은 참(True)으로 가고 절반은 거짓(False)으로 가면서 대열이 붕괴되는 현상이다.
- **동기화 비용(Synchronization Cost)**: 빨리 일을 끝낸 엘리트 코어가 굼벵이 코어를 기다리느라 결승선(배리어)에서 하염없이 낭비하는 치명적인 시간과 전기세이다.

</details>

| 병렬 실행 구조 | **단일 명령 다중 데이터** (SIMD) | **다중 명령 다중 데이터** (MIMD) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 데이터가 빼곡한 **조밀 텐서**, 무식한 행렬 연산 및 딥러닝 영상/음성 융단폭격 떡칠 처리 시 | 독립 웹 서버 서비스, 비동기 데이터베이스 쿼리 처리 및 조건문이 꼬인 **비정형 분기** 남발 시 |
| 아키텍처 핵심 구현 특징 | 뇌(제어)는 하나, 입(연산기)은 수백 개인 단일 확성기 인스트럭션 기반 획일적 데이터 레인 병렬화 가속 | 뇌도 입도 여러 개인 독립 코어 기반으로 각자도생하는 비동기 멀티스레드 작업 병렬화 실행 |
| 극복해야 할 태생적 한계점 | 조건문(if-else)을 만나면 참/거짓 중 하나만 실행하느라 나머지 절반의 레인이 멈춰버리는 분기 발산 붕괴 참사 | 잦은 코어 간 눈치싸움(통신)으로 낭비되는 끔찍한 **동기화 비용** 오버헤드 및 스케줄링 자원 낭비 |

#### 한줄 요약

- 단순 반복 융단폭격에는 무식하지만 힘센 SIMD(GPU)가 짱이고, 이것저것 꼬인 코드를 풀 땐 똑똑하고 독립적인 MIMD(멀티코어 CPU)가 짱이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **분기 발산(Branch Divergence)**: SIMD 레인 100개 중 50개는 If문을 타고 50개는 Else문을 탈 때, 두 길을 동시에 못 가니 50개 쉴 때 50개 일하고 번갈아 가며 놀아 성능이 반토막 나는 참사이다.
- **활성 마스크(Active Mask)**: 분기 발산이 터졌을 때, 이번 턴에 일할 놈은 '1', 놀 놈은 '0'으로 가면을 씌워(마스킹) 교통정리를 해주는 비정한 통제 장치이다.
- **동적 스케줄링(Dynamic Scheduling)**: 일찍 퇴근하려는 코어의 남은 일을 스케줄러가 강제로 뺏어서 굼벵이 코어에게 넘겨주거나, 그 반대로 남의 일을 훔쳐 오게(Work Stealing) 만드는 악독한 부하 분배이다.
- **부하 불균형(Load Imbalance)**: A 코어는 1초 만에 끝나고 B 코어는 10초 걸려서, 결승선에서 9초를 멍때리고 기다리며 전체 시스템을 갉아먹는 비효율의 극치이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 쓸데없는 조건문(if) 남발에 따른 치명적인 **분기 발산** 붕괴 및 값비싼 연산 레인이 반 토막 나 놀아버리는 유휴 참사 | **활성 마스크** 기반의 꼼수 커널 분리 및 데이터를 정렬해 if문을 최소화하는 사전 최적화 강제 적용 | 멈춰있는 잉여 레인 없이 하드웨어 활용률을 100%까지 멱살 잡고 끌어올려 전기세 낭비 박멸 |
| 엠아이엠디 코어 간 작업 난이도 연산량 차이로 인한 심각한 **부하 불균형** 잉여 낭비 대참사 발생 | 남의 일을 뻔뻔하게 훔쳐 오는 웤 스틸링(Work Stealing) 꼼수 기반 **동적 스케줄링** 전격 도입 | 전역 동기화 꼴찌 대기 시간(Barrier Wait)을 극적으로 찢어발겨 단축하여 클러스터 효율 극대화 달성 |
| 메모리 여기저기 불연속적으로 흩어진 데이터에 찔끔찔끔 접근하여 뿜어지는 에스아이엠디 대역폭 성능 마비 붕괴 | 메모리 뭉탱이 병합 접근(Coalescing) 적용 및 흩어진 데이터를 한 줄로 모으는 연속 데이터 레이아웃 강제 재배치 설계 | 느려터진 메모리 버스 트랜잭션 왕복 횟수를 파멸적으로 감소시켜 텐서 병목 완벽 제거 수호 |

#### 한줄 요약

- If문 붕괴는 마스크로 틀어막고(활성 마스크), 꿀 빠는 코어는 남의 일을 뺏어 굴리며(Work Stealing), 메모리는 무조건 한 줄로 정리해(Coalescing) 칩을 극한으로 부려먹어야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **병렬 실행 구조 선택 기준(Parallel Architecture Selection Criteria)**: 딥러닝 행렬을 갉아먹을 거냐, 아니면 구글 검색엔진을 돌릴 거냐에 따라 무식한 SIMD 가속기를 박을지 똑똑한 MIMD 멀티코어를 박을지 판가름하는 기준이다.

</details>

- **병렬 실행 구조 선택 기준**에 따라 조밀 데이터 동질 반복은 **단일 명령 다중 데이터**, 비정형 독립 쿼리 작업은 **다중 명령 다중 데이터** 선택을 단호히 결정함

#### 한줄 요약

- 단순 무식한 텐서 폭격은 SIMD(GPU)에 몰빵하고, 복잡하게 얽힌 다중 사용자의 잡다한 일처리는 MIMD(멀티코어 CPU)에 던져주는 것이 칩 설계의 불문율이다.
