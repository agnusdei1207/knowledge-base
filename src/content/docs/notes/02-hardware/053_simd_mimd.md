## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 하나의 명령어로 여러 개의 독립된 데이터 요소(벡터 레지스터)에 동일한 산술 논리 연산을 동시에 수행하는 데이터 병렬 처리 모델.
- **MIMD(Multiple Instruction, Multiple Data)**: 다수의 독립된 프로세서 또는 CPU 코어가 각자의 프로그램 카운터(PC)와 명령어 스트림에 따라 서로 다른 데이터를 비동기 실행하는 태스크 병렬 처리 모델.

</details>

- 정의/개념: 단일 명령어로 대량 데이터 벡터를 동시 연산하는 **SIMD(Single Instruction, Multiple Data)**와 독립 코어들이 상이한 태스크를 분산 실행하는 **MIMD(Multiple Instruction, Multiple Data) 프로세서 아키텍처**
- 배경/필요성: 단일 코어의 클록 주파수 증대 한계(전력 장벽)를 극복하기 위해 **데이터 병렬성(SIMD)과 태스크 수준 병렬성(MIMD)을 하드웨어 레벨에서 가속**

#### 한줄 요약
- SIMD는 동일 연산을 데이터 배열에 대량 적용하는 데이터 병렬 모델이고, MIMD는 독립 코어들이 서로 다른 작업을 비동기 실행하는 태스크 병렬 모델이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **벡터 레인(Vector Lane)**: SIMD 연산기 내부에서 1개의 데이터 요소(32비트/64비트)를 독립적으로 연산하는 하드웨어 산술 논리 경로.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: MIMD 환경에서 독립된 실행 문맥을 가진 여러 소프트웨어 스레드를 다중 코어에 분산하여 동시 실행하는 병렬성.

</details>

- 제어 회로 효율성 (SIMD): 단일 제어 장치(CU)를 수십~수백 개의 **벡터 레인(Vector Lane)**이 공유하므로 명령어 디코딩 오버헤드가 극소화되고 연산기 집적도 극대화
- 제어 유연성 및 복잡성 (MIMD): 각 코어가 독립 제어부와 PC를 가지므로 복잡한 분기 제어 및 **스레드 수준 병렬성(TLP)**을 완벽히 수용하나 캐시 일관성 오버헤드 수반
- 계층적 하이브리드 결합: 현대 프로세서는 **MIMD 멀티코어 칩셋 내부에 코어별 SIMD 벡터 유닛(AVX-512, Neon)을 집적**하여 두 병렬성을 통합 제공

#### 한줄 요약
- SIMD는 제어 공유로 연산 밀도를 높이고, MIMD는 독립 코어로 유연성을 확보하며, 현대 CPU는 둘을 계층적으로 결합한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **온칩 인터커넥트 패브릭(On-Chip Interconnect Fabric)**: MIMD 다중 코어 간에 L3 캐시 공유, 캐시 일관성(MESI) 메시지 및 메모리 트랜잭션을 고속 중계하는 온칩 상호 연결망.

</details>

```text
[SIMD 벡터 유닛 구조]                      [MIMD 멀티코어 프로세서 구조]
 ┌───────────────────────────┐             ┌───────────────┐ ┌───────────────┐
 │ 단일 제어 장치 (CU / PC)  │             │ 코어 0 (CU+PC)│ │ 코어 N (CU+PC)│
 └─────────────┬─────────────┘             │  └─ SIMD 유닛 │ │  └─ SIMD 유닛 │
   동일 명령어 │ 브로드캐스트              └───────┬───────┘ └───────┬───────┘
 ┌─────────────▼─────────────┐                     │                 │
 │ ┌───────┐ ┌───────┐┌───────┐│             ┌─────▼─────────────────▼─────┐
 │ │ALU/PU0│ │ALU/PU1││ALU/PUN││             │ 온칩 인터커넥트 (Mesh/Ring) │
 │ └───────┘ └───────┘└───────┘│             └──────────────┬──────────────┘
 │   벡터 레인 어레이 (D0~DN)  │                            ▼
 └───────────────────────────┘                [공유 L3 캐시 및 메모리 제어기]
```

선의 의미: 좌측은 단일 CU가 다중 PU로 동일 명령을 브로드캐스트하는 구조; 우측은 독립 코어들이 온칩 인터커넥트를 통해 협업하는 구조

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **SIMD 제어 장치** | 벡터 유닛 전단 | 단일 명령어를 인출·해독하여 모든 벡터 레인에 제어 신호 배포 | 1개 디코더 공유 |
| **벡터 레인 어레이** | SIMD 연산 코어 | 128~512비트 레지스터 내 요소별 산술 논리 연산 동시 실행 | 다중 ALU 레인 |
| **MIMD 독립 코어** | 칩 전역 분산 배치 | 독립된 PC와 제어 로직을 바탕으로 서로 다른 프로그램 스레드 실행 | 완전 독립 실행 문맥 |
| **온칩 인터커넥트** | 코어 간 중심망 | 다중 코어 간 **캐시 일관성(Snooping/Directory) 및 데이터 패킷 중계** | 링/메시 토폴로지 |
| **공유 LLC 및 IMC** | 칩 공통 메모리단 | 다중 코어와 벡터 유닛에 초광폭 대역폭 공급 및 메모리 직결 | 다채널 DDR5/HBM |

#### 한줄 요약
- SIMD는 단일 제어부와 다중 벡터 레인으로 구성되며, MIMD는 독립 코어들과 온칩 인터커넥트 및 공유 캐시로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 벡터화(Auto-Vectorization)**: C/C++ 컴파일러가 소스 코드의 순차 `for` 루프를 분석하여 데이터 의존성이 없을 때 자동으로 SIMD 벡터 명령어로 변환하는 최적화 기법.

</details>

```text
1. 응용 소프트웨어 병렬 연산 요청
                      │
                      ▼
2. 워크로드의 병렬성 성격 판정
   ┌──────────────────┴──────────────────┐
[ 비동기 다중 태스크 / 독립 스레드 ]   [ 대규모 정형 데이터 배열 / 행렬 루프 ]
   │                                     │
   ▼                                     ▼
3. MIMD 스레드로 분할 (Pthreads, OpenMP) 3. 컴파일러 자동 벡터화(Auto-Vectorization) 가능 여부
   │                                     ┌──────────┴──────────┐
   ▼                                   [ 자동 벡터화 실패 ]  [ 자동 벡터화 성공 ]
4. OS 스케줄러: 다중 코어에 분산 매핑    │                     │
   │                                     ▼                     ▼
   ▼                                   4. 내장 함수(Intrinsics)4. 512비트 SIMD 명령
5. 각 코어에서 독립 명령어 스트림 실행    수동 벡터화 구현      일괄 생성
   │                                     │                     │
   └──────────────────┬──────────────────┴─────────────────────┘
                      │
                      ▼
6. 멀티코어 상호연결망을 통한 캐시 일관성 유지 및 결과 병합 완료
```

분기 결과: **독립 태스크는** MIMD 코어로 분산 실행되며, **정형 데이터 루프는** SIMD 벡터 명령어로 변환되어 클록당 수십 배의 가속을 달성함

#### 한줄 요약
- 워크로드 판정 ➔ 독립 태스크는 MIMD 분산 ➔ 정형 루프는 SIMD 벡터화 ➔ 인터커넥트 동기화 ➔ 결과 병합 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | SIMD (벡터 프로세서 / GPU) | MIMD (멀티코어 CPU / 클러스터) |
|:---|:---|:---|
| 제어 장치 (CU) 구조 | **1개의 제어 장치를 다수 연산 레인이 공유** | **코어마다 독립적인 제어 장치(CU)와 PC 내장** |
| 병렬성 추구 수준 | **데이터 수준 병렬성 (Data-Level)** | **스레드/프로세스 수준 병렬성 (Thread-Level)** |
| 하드웨어 집적 효율 | **최고 (다이 면적당 순수 연산기 극대화)** | 중간 (제어 회로 및 캐시 중복 면적 소요) |
| 조건 분기 처리 | 취약 (분기 발산 시 레인 마스킹 유휴 발생) | **완벽 (각 코어가 독립 분기 예측 및 실행)** |
| 통신 및 동기화 | 레지스터 셔플 및 로컬 브로드캐스트 | **온칩 인터커넥트 캐시 일관성 및 락(Lock) 동기화** |
| 주요 적용 분야 | **AI 딥러닝 행렬곱, 영상/오디오 신호 처리** | **멀티태스킹 OS, 가상화 서버, 데이터베이스** |

#### 한줄 요약
- 행렬 연산과 대량 데이터 처리에는 SIMD가 압도적이며, 복잡한 비즈니스 로직과 멀티태스킹에는 MIMD가 필수적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **레인 마스킹(Lane Masking)**: SIMD 연산 시 `if-else` 조건에 부합하지 않는 특정 벡터 레인의 결과 쓰기를 하드웨어적으로 비활성화하는 기법.
- **작업 훔치기(Work-Stealing)**: MIMD 환경에서 유휴 상태가 된 코어가 부하가 많은 다른 코어의 작업 큐에서 태스크를 가져와 처리하는 부하 분산 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SIMD 연산 중 조건 분기로 인한 벡터 레인 유휴 | **조건 분기 제거 및 하드웨어 레인 마스킹(AVX-512 K-Mask) 적용** | 유효 레인 가동률 90% 이상 유지 |
| MIMD 스레드 간 부하 불균형으로 인한 배리어 대기 지연 | **동적 작업 훔치기(Work-Stealing) 런타임 스케줄러 적용** | 코어 유휴 시간 축소 및 처리량 25% 향상 |
| 비정렬 메모리 접근(Unaligned Access)에 따른 SIMD 성능 저하 | **메모리 64바이트 정렬(alignas) 및 배열 구조체(SoA) 변환** | 1사이클 연속 벡터 로드/스토어 달성 |
| MIMD 코어 수 증가에 따른 캐시 일관성 트래픽 포화 | **디렉터리 기반 일관성 및 데이터 소유권 격리(Thread-Local)** | 버스 대역폭 병목 해소 및 선형적 확장성 확보 |

#### 한줄 요약
- 실무에서는 레인 마스킹과 메모리 정렬로 SIMD를 극대화하고, 작업 훔치기와 일관성 최적화로 MIMD를 안정화한다.

## Ⅶ. 결론

- 고성능 컴퓨팅 시스템의 처리량을 극대화하기 위해 **대규모 정형 행렬 및 신호 처리 구간에는 SIMD/SIMT 벡터 연산기를 집중 배치**하고, **복잡한 제어 흐름과 멀티태스킹 구간에는 MIMD 멀티코어 아키텍처를 적용**하며, 컴파일러 계층에서는 **자동 벡터화와 OpenMP/MPI 기반 하이브리드 프로그래밍 모델**을 구축하는 통합 병렬 컴퓨팅 플랫폼 확립

#### 한줄 요약
- 현대 컴퓨터 구조는 MIMD의 유연한 제어와 SIMD의 막강한 연산 밀도를 결합하여 최고의 성능을 달성한다.
