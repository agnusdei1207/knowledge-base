## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 하나의 명령어로 여러 개의 데이터 요소에 동일한 연산을 동시에 수행하는 데이터 병렬 처리 모델.
- **MIMD(Multiple Instruction, Multiple Data)**: 여러 개의 독립적인 프로세서나 코어가 각자의 명령어 흐름에 따라 서로 다른 데이터를 비동기 실행하는 모델.

</details>

- 정의/개념: 단일 명령어로 다중 데이터를 일괄 연산하는 **SIMD(데이터 병렬성)** 와 독립 제어기로 다중 스레드를 분산 실행하는 **MIMD(태스크 병렬성)** 의 프로세서 아키텍처
- 배경/필요성: 전력 장벽으로 클록 상승이 제한된 뒤 정형 데이터와 독립 태스크의 서로 다른 병렬성을 함께 활용할 구조 필요

#### 한줄 요약
- 하나의 명령어로 대량 데이터를 한 번에 미는 SIMD와, 여러 코어가 각자 다른 일을 하는 MIMD로 병렬 처리를 구현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **벡터 레인(Vector Lane)**: SIMD 연산기 내부에서 하나의 데이터 요소를 독립적으로 계산하는 하드웨어 데이터 경로.
- **스레드 수준 병렬성(TLP)**: MIMD 환경에서 독립된 프로그램 스레드들을 다중 코어에 분산해 처리하는 병렬성.

</details>

- **SIMD**: 단일 제어 장치(CU)로 디코딩 오버헤드를 줄이고 대규모 루프/행렬 연산 극대화
- **MIMD**: 독립된 제어 장치와 프로그램 카운터(PC)를 통해 복잡한 분기문과 멀티태스킹 수용
- **계층형 결합**: 현대 프로세서는 멀티코어(MIMD) 내부 각 코어에 벡터 확장 유닛(SIMD)을 집적하여 복합 병렬성 실현

#### 한줄 요약
- 규칙적인 대량 계산은 SIMD 벡터 레인을 쓰고, 복잡한 비동기 작업은 MIMD 멀티코어에 나누어 담는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터커넥트망(Interconnect Network)**: MIMD 다중 코어 간에 캐시 일관성 메시지와 공유 메모리 접근을 중계하는 버스 또는 크로스바 네트워크.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ SIMD vs MIMD 프로세서 아키텍처 비교                         │
│                                                             │
│  [ SIMD 아키텍처 (단일 CU - 다중 ALUs) ]                     │
│  ┌────────────┐                                             │
│  │ 단일 제어부 │ ─── (동일 명령어 브로드캐스트) ────────────┐│
│  │ (Single CU)│                                            ││
│  └────────────┘                                            ││
│         │                                                  ││
│  ┌──────▼──────┐  ┌─────────────┐  ┌─────────────┐         ││
│  │ ALU Lane 0  │  │ ALU Lane 1  │  │ ALU Lane N  │         ││
│  └─────────────┘  └─────────────┘  └─────────────┘         ││
│                                                             │
│  [ MIMD 아키텍처 (독립 CU - 독립 ALU 코어들) ]              │
│  ┌────────────┐   ┌────────────┐   ┌────────────┐          ││
│  │ 코어 0 (CU)│   │ 코어 1 (CU)│   │ 코어 N (CU)│          ││
│  │   [ALU 0]  │   │   [ALU 1]  │   │   [ALU N]  │          ││
│  └──────┬─────┘   └──────┬─────┘   └──────┬─────┘          ││
│         │                │                │                ││
│  ┌──────┴────────────────┴────────────────┴──────────────┐ ││
│  │ 온칩 인터커넥트망 & 공유 LLC / 메인 메모리             │ ││
│  └───────────────────────────────────────────────────────┘ ││
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 상단 SIMD는 단일 제어부가 다수 ALU에 명령을 전달하며, 하단 MIMD는 각 코어가 독립 제어부와 연산기를 가짐

| 구성요소 | 책임 |
|:---|:---|
| SIMD 제어 장치 (Single CU) | 단일 명령어를 인출·디코딩하여 모든 벡터 레인에 동기화된 제어 신호 배포 |
| 벡터 연산 레인 (Vector ALU Lanes) | 배포된 제어 신호에 맞춰 각자의 데이터 레지스터 블록에 병렬 연산 동시 수행 |
| MIMD 독립 코어 (Core with CU/PU) | 독자적인 PC 레지스터를 기반으로 서로 다른 분기 및 서브루틴 코드 독립 실행 |
| 온칩 인터커넥트망 (NoC/Bus) | MIMD 코어들 간 데이터 교환, 배리어 동기화 및 캐시 일관성 트랜잭션 중계 |
| 공유 메모리 서브시스템 | 다중 코어 및 벡터 유닛에 고대역폭 데이터 스트림을 안정적으로 공급 |

#### 한줄 요약
- 단일 제어부와 다중 레인의 SIMD, 독립 제어부를 갖춘 다중 코어의 MIMD가 대조를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 벡터화(Auto-Vectorization)**: 컴파일러가 소스 코드의 순차 반복문을 분석하여 자동으로 SIMD 벡터 명령어로 변환하는 최적화.

</details>

```text
병렬 소프트웨어 프로그램 시작
      │
      ▼
1. 병렬성 프로파일링
      │
      ▼
2. MIMD 스레드 생성
      │
      ▼
3. SIMD 벡터 연산
      │
      ▼
4. 상태 동기화
      │
      ▼
5. 결과 집계
```

**동작 원리**

1. **병렬성 프로파일링**: 프로그램 내에서 제어 흐름 분기와 데이터 연속 반복문 구간을 분석
2. **MIMD 스레드 생성**: OpenMP/Pthreads 등을 통해 독립된 코어들에 작업 스레드 분산 배치
3. **SIMD 벡터 연산**: 각 코어가 AVX/NEON 등의 벡터 명령어로 한 번에 128~512비트 데이터 일괄 처리
4. **상태 동기화**: 코어 간 공유 메모리 접근 시 하드웨어 락 및 배리어(Barrier)를 통해 순서 보장
5. **결과 집계**: 각 코어 및 벡터 레인의 부분 결과를 합산(Reduce)하여 최종 메모리에 저장

#### 한줄 요약
- 워크로드 분할 → MIMD 스레드 분산 → 코어 내 SIMD 벡터 연산 → 동기화 → 결과 병합 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 병렬 프로세서 구조 | SIMD (벡터 유닛) | MIMD (멀티코어/클러스터) | SISD (단일 CPU) | MISD (특수 파이프라인) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 딥러닝 텐서·영상 처리·그래픽스 | 범용 서버·OS 멀티태스킹·클라우드 | 단순 임베디드 마이크로컨트롤러 | 우주항공 비행 제어 다중 중복 검증 |
| 핵심 특징 | 단일 명령어로 대량 데이터 고효율 일괄 처리 | 독립 코어들의 비동기 스레드 분산 실행 | 단일 제어-단일 연산의 결정적 순차 실행 | 단일 데이터에 다수 알고리즘 중복 적용 |
| 한계 | 조건 분기(if-else) 시 연산 레인 유휴 | 스레드 동기화 락 경합 및 통신 오버헤드 | 처리량 확장 불가 및 전력 장벽 한계 | 상용 소프트웨어 부재 및 구현 비용 과다 |

#### 한줄 요약
- 대용량 데이터는 SIMD, 다중 작업은 MIMD, 단순 제어는 SISD, 특수 안전은 MISD를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **마스킹(Masking)**: SIMD 연산 중 if-else 조건 불일치 레인의 결과를 무효화하여 분기 발산을 해결하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SIMD 조건 분기에 따른 **비활성 레인** 증가 | 분기 없는 코드와 프리디케이션 적용 | 유효 벡터 레인 비율 향상 |
| MIMD 스레드 간 **동기화 배리어 대기 및 부하 불균형(Load Imbalance)** | **워크 스틸링(Work-Stealing)** 동적 스케줄러 및 세분화 태스크 큐 적용 | 코어 유휴 시간 최소화 및 처리량 증대 |
| SIMD 비연속·비정렬 메모리 접근 | **SoA(Structure of Arrays)** 형태로 데이터 재배치 | 연속 벡터 로드와 캐시 라인 활용도 향상 |
| MIMD 코어 증가 시 **캐시 일관성 트래픽** 증가 | 데이터 소유권 분할과 디렉터리 기반 일관성 적용 | 공유 쓰기와 브로드캐스트 범위 축소 |

#### 한줄 요약
- 분기 제거로 SIMD 레인을 채우고, 워크 스틸링과 SoA 배열 정렬로 MIMD의 동기화와 메모리 병목을 해소한다.

## Ⅶ. 결론

- 정형 반복문은 **SIMD**, 독립 제어 태스크는 **MIMD**에 배치하고 계층적으로 결합
- GPU는 프로그래밍 관점의 SIMT와 하드웨어 실행 묶음을 구분해 적용

#### 한줄 요약
- 상위 태스크 수준의 MIMD 분산과 하위 루프 수준의 SIMD 벡터화를 결합한 이중 병렬 아키텍처로 컴퓨팅 성능을 극대화해야 한다.
