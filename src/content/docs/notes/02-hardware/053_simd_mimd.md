## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 하나의 명령어로 여러 개의 독립된 데이터 요소(벡터 레지스터)에 동일한 산술 논리 연산을 동시에 수행하는 데이터 병렬 처리 모델.
- **MIMD(Multiple Instruction, Multiple Data)**: 다수의 독립된 프로세서 또는 CPU 코어가 각자의 프로그램 카운터(PC)와 명령어 스트림에 따라 서로 다른 데이터를 비동기 실행하는 태스크 병렬 처리 모델.

</details>

- 정의/개념: 단일 명령어로 대량 데이터 벡터를 동시 연산하는 **SIMD**와 독립 코어들이 상이한 태스크를 분산 실행하는 **MIMD 프로세서 아키텍처**
- 배경/필요성: 단일 코어의 클록 주파수 향상 한계(Power Wall) 및 단일 명령어 흐름 방식의 **연산 처리량 확장성 한계 극복 및 데이터·태스크 병렬성 동시 수용 요구 증대**

#### 한줄 요약
- SIMD는 동일 연산을 데이터 배열에 대량 적용하는 데이터 병렬 모델이고, MIMD는 독립 코어들이 서로 다른 작업을 비동기 실행하는 태스크 병렬 모델이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **벡터 레인(Vector Lane)**: SIMD 연산기 내부에서 1개의 데이터 요소(32비트/64비트)를 독립적으로 연산하는 하드웨어 산술 논리 경로.
- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: MIMD 환경에서 독립된 실행 문맥을 가진 여러 소프트웨어 스레드를 다중 코어에 분산하여 동시 실행하는 병렬성.

</details>

- 제어 회로 효율성 (SIMD): 단일 제어 장치를 다수의 **벡터 레인**이 공유하여 디코딩 오버헤드를 줄이고 연산기 집적도 극대화
- 제어 유연성 및 복잡성 (MIMD): 독립 제어부와 PC를 통해 **스레드 수준 병렬성(TLP)**을 완벽히 수용하나 캐시 일관성 오버헤드 수반
- 계층적 하이브리드 결합: 현대 프로세서는 MIMD 멀티코어 내부에 **SIMD** 벡터 유닛을 집적하여 두 병렬성을 통합 제공

#### 한줄 요약
- SIMD는 제어 공유로 연산 밀도를 높이고, MIMD는 독립 코어로 유연성을 확보하며, 현대 CPU는 둘을 계층적으로 결합한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **온칩 인터커넥트 패브릭(On-Chip Interconnect Fabric)**: MIMD 다중 코어 간에 L3 캐시 공유, 캐시 일관성(MESI) 메시지 및 메모리 트랜잭션을 고속 중계하는 온칩 상호 연결망.

</details>

```text
[SIMD 및 MIMD 프로세서 계층 구조]
  │
  ├─ [SIMD 아키텍처] (데이터 병렬 서브시스템)
  │     ├─ [단일 제어 장치] (CU, 단일 명령어 인출/해독)
  │     ├─ [병렬 벡터 레인군] (레인 0~N ALU 동시 연산)
  │     └─ [광대역 벡터 레지스터] (512/1024비트 VREG 파일)
  │
  └─ [MIMD 아키텍처] (태스크 병렬 서브시스템)
        ├─ [다중 독립 코어군] (코어별 독립 CU/PC 및 L1/L2)
        ├─ [온칩 상호연결 패브릭] (링/메시 버스, MESI 프로토콜)
        └─ [공유 메모리 서브시스템] (공유 L3 캐시 및 통합 IMC)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| SIMD 제어 장치 | 1개 디코더로 모든 벡터 레인 제어 |
| 벡터 레인 어레이 | 요소별 산술 논리를 다중 ALU 레인에서 실행 |
| MIMD 독립 코어 | 독립 PC 기반의 실행 문맥 처리 |
| 온칩 인터커넥트 | 코어 간 캐시 일관성 메시지 중계 |
| 공유 LLC 및 IMC | 다중 코어에 DDR5/HBM 대역폭 공급 |

#### 한줄 요약
- SIMD는 디코더 하나를 모든 레인이 공유해 제어 회로를 복제하지 않는 대신 레인마다 다른 일을 시킬 수 없고, MIMD는 코어마다 실행 문맥을 두는 대가로 코어 간 일관성 메시지를 중계할 온칩 인터커넥트와 공유 LLC 계층을 새로 떠안는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 벡터화(Auto-Vectorization)**: C/C++ 컴파일러가 소스 코드의 순차 `for` 루프를 분석하여 데이터 의존성이 없을 때 자동으로 SIMD 벡터 명령어로 변환하는 최적화 기법.

</details>

```text
+-------------------------------------------------------------+
|                응용 소프트웨어 병렬 연산 요청               |
+-------------------------------------------------------------+
                               │
                               ▼
               +-------------------------------+
               | 1. 워크로드 병렬성 유형 판정  |
               +-------------------------------+
                      |                 |
             [비동기 독립 태스크(TLP)]  | [대규모 정형 배열 루프(DLP)]
                      |                 v
                      | +-------------------------------+
                      | | 2. 컴파일러 데이터 의존성 분석|
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 3. 자동 벡터화(Auto-Vectorize)|
                      | +-------------------------------+
                      |                 |
                      v                 v
+-----------------------+ +-------------------------------+
| 2. MIMD 태스크 분할   | | 4. 단일 명령어로 벡터 레인    |
| 3. OS 코어 디스패치   | |    일괄 병렬 연산             |
| 4. 독립 명령어(IS)실행| +-------------------------------+
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
| 5. 온칩 패브릭 캐시 일관성 유지 및 최종 연산 결과 기록      |
+-------------------------------------------------------------+
```

- 분기 결과: 독립 태스크는 **MIMD** 스레드로 분산 실행되며 정형 데이터 루프는 **SIMD** 벡터화로 가속됨

**동작 원리**

1. **병렬성 유형 분석**: 프로그램 실행 시 워크로드가 스레드 수준 병렬성(TLP)인지 데이터 수준 병렬성(DLP)인지 분석하여 실행 경로 분기
2. **태스크 분할 및 루프 의존성 분석**: 독립적 비동기 로직은 OpenMP/스레드 풀로 분할하고, 반복 행렬 루프는 컴파일러가 루프 간 데이터 의존성 검증
3. **스케줄링 및 벡터화**: MIMD 태스크는 OS 스케줄러에 의해 물리 코어로 분배되며, SIMD 루프는 벡터화 엔진에 의해 AVX-512 등의 팩트(Packed) 명령어로 변환
4. **명령어 스트림 디스패치**: MIMD 코어는 각자의 PC를 바탕으로 독립 명령어를 인출해 실행하고, SIMD 코어는 단일 디코더에서 여러 ALU 레인으로 동시 연산 제어 신호 방출
5. **동기화 및 결과 기록**: 연산 완료 시 MIMD는 온칩 인터커넥트 기반 캐시 일관성 프로토콜(MESI)로 동기화하고, SIMD는 레지스터 쓰기 후 최종 결과를 메모리에 일괄 저장

#### 한줄 요약
- 독립 태스크는 MIMD 스레드로, 정형 루프는 SIMD 벡터화로 갈리므로, 데이터 의존성과 제어 흐름의 규칙성을 먼저 판정해야 어느 병렬성이 비용 대비 이득인지 결정된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **레인 마스킹(Lane Masking)**: SIMD 연산 시 `if-else` 조건에 부합하지 않는 특정 벡터 레인의 결과 쓰기를 하드웨어적으로 비활성화하는 기법.

</details>

| 대상 구분 | SIMD (벡터 프로세서 / GPU) | MIMD (멀티코어 CPU / 클러스터) |
|:---|:---|:---|
| 적용 기준 | 대규모 정형 데이터 동종 연산(AI 행렬곱, 영상/신호처리) 요구 시 | 독립 멀티스레드 태스크 및 복잡 비즈니스 분기 처리 요구 시 |
| 핵심 특징 | 단일 CU 디코더 공유, **초광폭 벡터 레인 어레이 집적**, 데이터 수준 병렬성(DLP) 극대화 | 코어별 독립 CU/PC 내장, **스레드 수준 병렬성(TLP)** 수용, 비동기 분산 제어 |
| 한계 | 조건 분기 시 **레인 마스킹**에 따른 유휴(Divergence), 메모리 비정렬 시 성능 저하 | 제어 회로 및 L1/L2 캐시 면적 중복 오버헤드, 캐시 일관성 트래픽 및 락 경합 |

#### 한줄 요약
- 행렬 연산과 대량 데이터 처리에는 SIMD가 압도적이며, 복잡한 비즈니스 로직과 멀티태스킹에는 MIMD가 필수적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **작업 훔치기(Work-Stealing)**: MIMD 환경에서 유휴 상태가 된 코어가 부하가 많은 다른 코어의 작업 큐에서 태스크를 가져와 처리하는 부하 분산 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SIMD 연산 중 조건 분기로 인한 벡터 레인 유휴 | **하드웨어 레인 마스킹** 및 분기 제거 적용 | 유효 레인 가동률 90% 이상 유지 |
| MIMD 스레드 간 부하 불균형으로 인한 배리어 대기 지연 | 동적 **작업 훔치기(Work-Stealing)** 스케줄러 적용 | 코어 유휴 시간 축소 및 처리량 대폭 향상 |
| 비정렬 메모리 접근에 따른 SIMD 성능 저하 | **메모리 정렬** 및 구조체 배열(SoA) 변환 | 1사이클 연속 벡터 로드/스토어 달성 |
| MIMD 코어 수 증가에 따른 캐시 일관성 트래픽 포화 | **디렉터리 기반 일관성** 및 스레드 로컬 격리 | 버스 대역폭 병목 해소 및 선형적 확장성 확보 |

#### 한줄 요약
- 실무에서는 레인 마스킹과 메모리 정렬로 SIMD를 극대화하고, 작업 훔치기와 일관성 최적화로 MIMD를 안정화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SoA(Structure of Arrays)**: 데이터 구조를 배열의 구조체(AoS) 대신 구조체의 배열로 재구성하여 연속 메모리 로드를 가능하게 하는 SIMD 친화적 메모리 레이아웃.
- **MESI 프로토콜**: 멀티프로세서 환경에서 Modified, Exclusive, Shared, Invalid 4가지 상태를 통해 L1/L2 캐시의 데이터 일관성을 하드웨어적으로 유지하는 프로토콜.

</details>

- 대규모 데이터 병렬성을 위한 SIMD와 유연한 멀티태스킹을 위한 MIMD는 상호 배타적 대립이 아닌 상호 보완적 표준으로 자리 잡았으며, 현대 컴퓨팅은 멀티코어 CPU(MIMD) 기반 위에 매니코어 GPU 가속기(SIMD/SIMT)가 결합된 이종 하이브리드 아키텍처로 고착화 진행 중.
- 소프트웨어 아키텍트는 알고리즘의 제어 분기와 데이터 규칙성을 측정하여 정형 루프는 SIMD 벡터 엔진에, 비동기 분기 로직은 MIMD 멀티스레드 코어에 최적 매핑하는 이종 컴퓨팅 파이프라인 설계 체계 확립 필수.

#### 한줄 요약
- 현대 컴퓨터 구조는 MIMD의 유연한 제어와 SIMD의 막강한 연산 밀도를 결합하여 최고의 성능을 달성한다.
