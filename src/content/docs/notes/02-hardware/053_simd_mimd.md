## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction Multiple Data)**: 1개의 제어 유닛(PC)이 브로드캐스트하는 단일 명령어로 다수의 ALU 데이터 레인을 동시에 구동하는 데이터 병렬 처리 방식.
- **MIMD(Multiple Instruction Multiple Data)**: 다수의 독립적인 프로세서/코어가 각자의 제어 유닛과 프로그램 카운터(PC)를 가지고 서로 다른 명령어와 데이터를 비동기 실행하는 작업 병렬 처리 방식.
- **계층형 병렬성(Hierarchical Parallelism)**: 코어 간 MIMD 구조와 코어 내부 SIMD 구조를 유기적으로 결합한 현대 프로세서 아키텍처.

</details>

- 정의/개념: 단일 명령어로 다수의 데이터를 동시 처리하는 데이터 병렬성(SIMD)과, 다수의 독립 코어가 서로 다른 명령어를 비동기 처리하는 작업 병렬성(MIMD)의 구조적 차이 및 하이브리드 결합 체계
- 배경/필요성: 분기 처리에 취약한 SIMD의 한계와 단일 작업 디코딩 오버헤드가 큰 MIMD의 한계를 상호 보완하여, **현대 멀티코어 및 GPU 시스템의 계층적 연산 효율 극대화**

#### 한줄 요약

- 코어 간 **MIMD 작업 병렬성과 코어 내 SIMD 데이터 병렬성을 결합**하여 연산 효율 극대화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Common Instruction(공통 명령어)**: 디코딩 오버헤드를 줄이기 위해 다수의 ALU에 동일하게 전달되는 단일 제어 신호.
- **Independent Program Counter(독립 PC)**: 각 코어가 독립적인 제어 흐름과 함수 호출, 조건 분기를 수행할 수 있도록 지원하는 레지스터.

</details>

- 디코딩 전력 낭비를 줄이고 대규모 행렬/벡터 연산을 가속하는 **단일 명령(Common Instruction) 기반 코어 내 SIMD 레인**
- 서로 다른 OS 스레드와 비동기 작업을 독립적으로 처리하는 **다중 제어 흐름(Independent PC) 기반 코어 간 MIMD**
- 노드 레벨 스레드 분배와 코어 레벨 벡터화를 결합한 **계층형 병렬성(Hierarchical Parallelism)**

#### 한줄 요약

- **코어 내 공통 명령(SIMD)·코어 간 독립 PC(MIMD)·계층형 병렬성(Hierarchical)** 결합

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Execution Lane(실행 레인)**: 동일한 SIMD 명령어를 인가받아 데이터 청크를 병렬로 가공하는 물리적 연산 파이프라인.
- **Barrier(배리어)**: 비동기로 동작하는 MIMD 코어들이 특정 실행 지점에 도달할 때까지 대기하여 데이터 정합성을 맞추는 동기화 메커니즘.

</details>

```text
[ SIMD & MIMD 계층적 결합 아키텍처 구조도 ]
┌─────────────────────────────────────────────────────────────┐
│ OS 작업 큐 (Work Queue : 다중 스레드 풀)                     │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ MIMD 스케줄러 (독립 코어로 스레드 비동기 디스패치)           │
└──────┬───────────────────────┼───────────────────────┬──────┘
       │ (Thread 0)            │ (Thread 1)            │ (Thread N)
┌──────▼──────┐         ┌──────▼──────┐         ┌──────▼──────┐
│ Core 0 (PC0)│         │ Core 1 (PC1)│         │ Core N (PCN)│
│ ┌─────────┐ │         │ ┌─────────┐ │         │ ┌─────────┐ │
│ │SIMD Lane│ │         │ │SIMD Lane│ │         │ │SIMD Lane│ │
│ │ 0, 1, 2 │ │         │ │ 0, 1, 2 │ │         │ │ 0, 1, 2 │ │
│ └─────────┘ │         │ └─────────┘ │         │ └─────────┘ │
└──────┬──────┘         └──────┬──────┘         └──────┬──────┘
       │                       │                       │
═══════╧═══════════════════════╧═══════════════════════╧══════ (공유 메모리 & Barrier 동기화)
```

선의 의미: 작업 큐, MIMD 스케줄러, 멀티코어 및 코어 내부 SIMD 레인, 공유 메모리/동기화 배리어 간의 하이브리드 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 독립 작업 큐 대기열 | 다중 독립 스레드 단위 작업 패킷의 큐잉 대기 및 스케줄러로 던지기 전 멱살 통제 제어 |
| 엠아이엠디(MIMD) 스케줄러 | 놀고 있는 꿀 빠는 유휴 코어를 색출하고, 각기 다른 비동기 작업을 쉴 틈 없이 디스패칭 분배 수행 |
| 에스아이엠디(SIMD) 지원 코어군 | 코어 독립 실행 통제 및 그 내부 하드웨어 벡터 **연산 레인**의 무자비한 융단폭격 병렬 연산 수행 |
| 공유 메모리 및 동기화기 | 코어 간 계산 끝난 텐서 공유 및 가장 느린 놈을 기다리는 전역 **배리어** 동기화 래칭 철저 통제 |

#### 한줄 요약

- **독립 작업 큐·MIMD 스케줄러·SIMD 지원 멀티코어·공유 메모리 & Barrier 동기화**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Vectorization(벡터화)**: 루프(Loop) 형태의 직렬 코드를 컴파일러가 분석하여 단일 SIMD 명령어로 변환하는 최적화 기법.

</details>

```text
[ MIMD 스케줄링 및 SIMD 벡터 연산 흐름 ]
                         │
                         ▼
   [ 1. MIMD 스케줄러가 작업 큐에서 태스크 디스크립터 인출 ]
                         │
                         ▼
   [ 2. 독립 코어(Core 0~N)로 각기 다른 비동기 스레드 할당 ]
                         │
        +─────────────────────────────────────────+
        │ 각 코어 내부 고속 벡터 연산 구간       │
        │   3. 단일 명령으로 SIMD 레인 다중 데이터│
        │      병렬 연산 융단폭격 수행            │
        +─────────────────────────────────────────+
                         │
                         ▼
   [ 4. 코어별 연산 결과 텐서를 L3/공유 메모리에 기록 및 취합 ]
                         │
                         ▼
   [ 5. 모든 코어 완료 대기 (Barrier 동기화 래치 해제) ]
```

**동작 원리**

1. **태스크 디스패치**: MIMD 스케줄러가 대기열에서 독립적인 작업을 인출하여 코어별로 전달
2. **독립 비동기 실행**: 각 코어가 독립된 PC를 기반으로 제어 흐름 및 분기 실행
3. **SIMD 벡터 연산**: 코어 내부의 고밀도 데이터 루프를 단일 SIMD 명령어로 다중 레인에서 병렬 실행
4. **결과 취합**: 계산 완료된 중간 텐서를 캐시 계층 및 전역 공유 메모리에 커밋
5. **전역 Barrier 동기화**: 모든 코어의 작업 완료를 확인한 후 다음 동기화 블록으로 전진

#### 한줄 요약

- 작업 큐 디스패치 $\to$ **MIMD 코어 비동기 할당 $\to$ 코어 내 SIMD 벡터 연산 $\to$ 공유 메모리 취합 $\to$ 전역 Barrier 동기화**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIMD vs MIMD 비교**:
  - SIMD: 데이터 병렬성, 1 PC, 조밀 텐서 최적, 분기 발산 한계
  - MIMD: 작업 병렬성, 다수 PC, 독립 태스크 최적, 동기화 오버헤드

</details>

| 비교 항목 | SIMD (단일 명령 다중 데이터) | MIMD (다중 명령 다중 데이터) |
|:---|:---|:---|
| 병렬성 및 제어 방식 | 데이터 병렬성, 단일 제어 유닛(1 PC) 확성기 제어 | 작업/스레드 병렬성, 다중 독립 제어 유닛(다수 PC) |
| 최적 워크로드 및 효율 | 조밀 텐서(Dense), 정형 루프, 높은 연산 밀도 | 비정형 분기(if-else), 독립 트랜잭션, 높은 유연성 |
| 한계 및 오버헤드 | 분기 발산(Divergence) 시 레인 유휴, 비정형 처리 한계 | 코어 간 동기화 오버헤드, 스케줄링 및 제어 로직 낭비 |

#### 한줄 요약

- 정형 대량 연산은 **SIMD**, 비정형 복잡 작업은 **MIMD**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Branch Divergence(분기 발산)**: SIMD 레인들 내에서 서로 다른 if/else 분기를 탈 때 비활성 레인이 멈추는 현상.
- **Work Stealing**: 유휴 코어가 바쁜 코어의 작업 큐에서 태스크를 훔쳐와 부하 균형을 맞추는 스케줄링.
- **Memory Coalescing**: 인접한 SIMD 레인들이 요청하는 메모리 주소를 단일 트랜잭션으로 병합하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 쓸데없는 조건문(if) 남발에 따른 치명적인 **분기 발산** 붕괴 및 값비싼 연산 레인이 반 토막 나 놀아버리는 유휴 참사 | **활성 마스크** 기반의 꼼수 커널 분리 및 데이터를 정렬해 if문을 최소화하는 사전 최적화 강제 적용 | 멈춰있는 잉여 레인 없이 하드웨어 활용률을 100%까지 멱살 잡고 끌어올려 전기세 낭비 박멸 |
| 엠아이엠디 코어 간 작업 난이도 연산량 차이로 인한 심각한 **부하 불균형** 잉여 낭비 대참사 발생 | 남의 일을 뻔뻔하게 훔쳐 오는 웤 스틸링(Work Stealing) 꼼수 기반 **동적 스케줄링** 전격 도입 | 전역 동기화 꼴찌 대기 시간(Barrier Wait)을 극적으로 찢어발겨 단축하여 클러스터 효율 극대화 달성 |
| 메모리 여기저기 불연속적으로 흩어진 데이터에 찔끔찔끔 접근하여 뿜어지는 에스아이엠디 대역폭 성능 마비 붕괴 | 메모리 뭉탱이 병합 접근(Coalescing) 적용 및 흩어진 데이터를 한 줄로 모으는 연속 데이터 레이아웃 강제 재배치 설계 | 느려터진 메모리 버스 트랜잭션 왕복 횟수를 파멸적으로 감소시켜 텐서 병목 완벽 제거 수호 |

#### 한줄 요약
