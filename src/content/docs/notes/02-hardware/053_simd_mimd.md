## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 하나의 명령어로 여러 개의 데이터 요소에 동일한 연산을 동시에 수행하는 데이터 병렬 처리 모델.
- **MIMD(Multiple Instruction, Multiple Data)**: 여러 개의 독립적인 프로세서나 코어가 각자의 명령어 흐름에 따라 서로 다른 데이터를 비동기 실행하는 모델.

</details>

- 정의/개념: 명령어 하나로 여러 데이터를 처리하는 **SIMD(Single Instruction, Multiple Data)**와 독립 제어 흐름을 여러 개 두는 **MIMD(Multiple Instruction, Multiple Data)**의 대비 구조
- 배경/필요성: 클록을 더 올릴 수 없게 된 뒤 성능을 병렬성에서 얻어야 했고, 정형 데이터와 독립 태스크는 서로 다른 방식의 병렬성을 요구

#### 한줄 요약
- 둘은 성능 등급이 아니라 코드의 성격에 대응하므로, 어느 쪽을 쓸지는 하드웨어가 아니라 반복문이 규칙적인지가 정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **벡터 레인(Vector Lane)**: SIMD 연산기 내부에서 하나의 데이터 요소를 독립적으로 계산하는 하드웨어 데이터 경로.
- **스레드 수준 병렬성(TLP)**: MIMD 환경에서 독립된 프로그램 스레드들을 다중 코어에 분산해 처리하는 병렬성.

</details>

- SIMD는 제어 회로를 **벡터 레인(Vector Lane)** 전체가 공유해 명령어 해독 비용을 나눔
- MIMD는 코어마다 독립 제어 흐름을 두어 **스레드 수준 병렬성(TLP)**과 복잡한 분기를 수용
- 현대 프로세서는 멀티코어 안의 각 코어에 벡터 유닛을 넣어 두 병렬성을 계층으로 결합

#### 한줄 요약
- SIMD는 제어 비용을 나눠 이득을 얻고 MIMD는 제어를 복제해 자유를 얻으므로, 두 구조의 차이는 제어 회로를 공유하느냐 하나로 요약된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터커넥트망(Interconnect Network)**: MIMD 다중 코어 간에 캐시 일관성 메시지와 공유 메모리 접근을 중계하는 버스 또는 크로스바 네트워크.

</details>

```text
[SIMD 구조]
├─ 단일 제어부 (명령어 인출·해독 후 브로드캐스트)
└─ 벡터 연산 레인 × N (동일 연산·서로 다른 데이터)

[MIMD 구조]
├─ 독립 코어 × N
│  ├─ 자체 제어부·프로그램 카운터
│  └─ 자체 연산기
├─ 온칩 인터커넥트망 (일관성·동기화 메시지 중계)
└─ 공유 LLC·주기억장치
```

선의 의미: 가지(`├─`)는 소유 관계이며, 두 구조의 차이는 제어부가 하나인지 코어마다 복제되는지 한 지점에서 갈림

| 구성요소 | 책임 |
|:---|:---|
| SIMD 제어부 | 명령어 하나를 해독해 모든 레인에 동기 신호 배포 |
| 벡터 레인 | 같은 제어 신호로 각자의 데이터에 병렬 연산 수행 |
| MIMD 독립 코어 | 자체 프로그램 카운터로 서로 다른 코드 경로 실행 |
| **인터커넥트망(Interconnect Network)** | 코어 간 데이터 교환·동기화·일관성 메시지 중계 |
| 공유 메모리 서브시스템 | 다중 코어 및 벡터 유닛에 고대역폭 데이터 스트림을 안정적으로 공급 |

#### 한줄 요약
- MIMD에만 인터커넥트망이 필요한 이유는 독립 실행이 곧 상태 불일치를 뜻하기 때문이며, 자유의 대가가 통신 회로로 청구된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **자동 벡터화(Auto-Vectorization)**: 컴파일러가 소스 코드의 순차 반복문을 분석하여 자동으로 SIMD 벡터 명령어로 변환하는 최적화.

</details>

```text
병렬 소프트웨어 실행 시작
        │
   구간의 병렬성 성격은 무엇인가?
   ┌────┴─────────┐
독립 태스크        정형 반복문
   │                 │
MIMD 스레드로       컴파일러가 자동 벡터화 가능한가?
코어에 분산          ┌──┴───┐
   │              아니오     예
   │                │        │
   │           내장 함수로  SIMD 명령으로
   │           수동 벡터화   일괄 처리
   └────┬───────────┴────────┘
        │
   배리어·락으로 코어 간 상태 동기화
        │
   부분 결과 합산 후 저장
```

분기 결과: 두 병렬성은 배타적이지 않고 겹쳐 쓰이므로 실제 프로그램은 바깥 루프를 코어에 나누고 안쪽 루프를 레인에 나누며, 어느 한쪽만 쓰면 나머지 자원이 통째로 논다

#### 한줄 요약
- **자동 벡터화(Auto-Vectorization)**가 성공하느냐가 실질적 갈림길이며, 실패하면 같은 코드가 벡터 유닛을 하나도 쓰지 못한 채 돌아간다.

## Ⅴ. 종류 및 비교

| 병렬 프로세서 구조 | SIMD (벡터 유닛) | MIMD (멀티코어/클러스터) | SISD (단일 CPU) | MISD (특수 파이프라인) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 딥러닝 텐서·영상 처리·그래픽스 | 범용 서버·OS 멀티태스킹·클라우드 | 단순 임베디드 마이크로컨트롤러 | 우주항공 비행 제어 다중 중복 검증 |
| 핵심 특징 | 단일 명령어로 대량 데이터 고효율 일괄 처리 | 독립 코어들의 비동기 스레드 분산 실행 | 단일 제어-단일 연산의 결정적 순차 실행 | 단일 데이터에 다수 알고리즘 중복 적용 |
| 한계 | 조건 분기(if-else) 시 연산 레인 유휴 | 스레드 동기화 락 경합 및 통신 오버헤드 | 처리량 확장 불가 및 전력 장벽 한계 | 상용 소프트웨어 부재 및 구현 비용 과다 |

#### 한줄 요약
- 네 구조는 제어 흐름을 몇 개 두고 데이터를 몇 갈래로 흘리느냐의 조합일 뿐이며, 실제 칩은 이 조합을 계층마다 다르게 골라 겹쳐 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **마스킹(Masking)**: SIMD 연산 중 if-else 조건 불일치 레인의 결과를 무효화하여 분기 발산을 해결하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 조건 분기로 비활성 벡터 레인 증가 | 분기 없는 코드 작성과 **마스킹(Masking)** 적용 | 유효 레인 비율 향상 |
| 스레드 간 부하 불균형으로 배리어 대기 발생 | 작업 훔치기 스케줄러와 세분화된 태스크 큐 적용 | 코어 유휴 시간 축소로 처리량 증대 |
| 비연속·비정렬 메모리 접근으로 벡터 로드 실패 | 구조체 배열 형태로 데이터 재배치 | 연속 벡터 로드와 캐시 라인 활용도 향상 |
| 코어 증가에 따라 캐시 일관성 트래픽 급증 | 데이터 소유권 분할과 디렉터리 기반 일관성 적용 | 공유 쓰기와 브로드캐스트 범위 축소 |

#### 한줄 요약
- 두 구조의 대책이 각각 레인을 채우는 일과 코어를 놀리지 않는 일로 갈리듯, 병렬 최적화는 자원을 늘리는 문제가 아니라 비어 있는 자원을 찾는 문제다.

## Ⅶ. 결론

- 정형 반복문은 SIMD 레인에, 독립 제어 태스크는 MIMD 코어에 배치해 계층적으로 결합하고, GPU에서는 프로그래밍 모델과 하드웨어 실행 묶음을 구분해 판단

#### 한줄 요약
- 두 축 중 하나만 쓰는 프로그램은 하드웨어의 절반을 버리는 셈이며, 실제 성능 격차는 대개 코어 수가 아니라 이 이중 구조를 썼는지에서 벌어진다.
