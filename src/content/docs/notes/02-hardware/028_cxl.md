## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link)**: 고속 상호 연결 물리 계층 위에서 프로세서와 장치 간 하드웨어 캐시 일관성 및 메모리 접근을 보장하는 개방형 인터커넥트 규격이다.
- **분리 주소 공간(Disjoint Address Space)**: 가속기 장치가 호스트와 격리된 독자 주소 공간을 가짐으로써 발생하는 비효율적인 데이터 복사 오버헤드 구조이다.
- **메모리 풀링(Memory Pooling)**: 서버 내의 대용량 확장 메모리를 중앙 공유 풀로 구축하고, 각 컴퓨팅 노드가 필요 용량을 동적으로 할당받아 사용하는 아키텍처이다.

</details>

- 정의: 물리 계층 위에서 입출력, 캐시, 메모리 프로토콜을 다중화하여 장치 간 **하드웨어 캐시 일관성**과 메모리 확장을 지원하는 오픈 인터커넥트 아키텍처
- 배경: 기존 **분리 주소 공간**의 심각한 복사 오버헤드를 극복하고 물리적 한계를 초월한 **메모리 풀링**을 달성하기 위함

#### 한줄 요약

- 개방형 물리 계층 위에서 3대 프로토콜을 결합하여, 캐시 일관성을 유지하면서 대규모 메모리의 동적 확장과 풀링을 가능하게 하는 인터커넥트이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **입출력 프로토콜(CXL.io)**: 장치 열거, 비일관적 입출력, 직접 메모리 접근 및 장치 설정을 전담하는 기본 필수 프로토콜이다.
- **캐시 프로토콜(CXL.cache)**: 가속기 장치가 호스트 프로세서의 메인 메모리를 저지연으로 직접 접근하고 캐싱할 수 있도록 지원하는 프로토콜이다.
- **메모리 프로토콜(CXL.mem)**: 호스트가 확장 장치 메모리를 일반 메모리 공간처럼 투명하게 직접 접근하게 만드는 프로토콜이다.
- **프로토콜 다중화(Protocol Multiplexing)**: 단일 물리 링크 상에서 3종의 서로 다른 프로토콜 패킷을 시분할하여 병렬 전송하는 하드웨어 기술이다.

</details>

- 단일 물리 링크 위에서 **입출력 프로토콜**, **캐시 프로토콜**, **메모리 프로토콜**을 묶는 **프로토콜 다중화** 구동 기술을 적용함.
- **메모리 프로토콜**을 통해 소켓의 물리적 한계를 넘어서는 테라바이트급 확장 메모리를 일반 메모리로 투명하게 할당함.
- 장치 유형에 맞는 **하드웨어 캐시 일관성**과 직관적인 메모리 접근을 제공하여 명시적인 데이터 복사를 극적으로 감소시킴.

#### 한줄 요약

- 단일 물리 배선 위에 3대 전용 프로토콜을 다중화하여 싣고, 장치 간 일관성 유지와 거대 메모리 확장의 물리적 토대를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트 포트(CXL Root Port)**: 프로세서 소켓 내부에 집적되어 연결망 트랜잭션을 발송하고 수신하는 호스트 측의 최상위 제어 포트이다.
- **스위치(CXL Switch)**: 다중 호스트와 다수의 확장 장치 사이를 십자형으로 연결하여 트래픽을 크로스바 스위칭해 주는 인터커넥트 스위치이다.
- **패브릭(CXL Fabric)**: 스위치와 패브릭 관리자를 통해 서버 랙 전체의 메모리를 논리적 주소 공간으로 동적 할당 및 분해하는 메쉬 네트워크이다.

</details>

```text
[ 다중 호스트 컴퓨트 익스프레스 링크 아키텍처 ]
+-------------------------+         +-------------------------+
| 호스트 프로세서 1       |         | 호스트 프로세서 2       |
| (최상위 루트 포트 내장) |         | (최상위 루트 포트 내장) |
+-------------------------+         +-------------------------+
             │ (입출력 / 캐시 / 메모리 프로토콜) │
             +------------------+----------------+
                                │
                        [ 스위치 패브릭 ]
                                │
        +-----------------------+-----------------------+
        ▼                       ▼                       ▼
 [ 타입 1 장치 ]         [ 타입 2 장치 ]         [ 타입 3 장치 ]
 (지능형 네트워크 카드)  (텐서 연산 가속기)      (거대 메모리 확장기)
 (입출력 + 캐시)         (입출력+캐시+메모리)    (입출력 + 메모리)
```

| 구성요소 | 책임 |
|:---|:---|
| **입출력 프로토콜** | 가속기 및 메모리 장치 검색, 기본 설정 및 비일관적 입출력 통신 제공 |
| **캐시 프로토콜** | 가속기 장치의 호스트 메인 메모리에 대한 하드웨어 수준의 일관적 캐싱 지원 |
| **메모리 프로토콜** | 호스트의 확장 장치 메모리에 대한 직접적이고 투명한 읽기 쓰기 엑세스 지원 |
| 스위치 및 패브릭 | 다중 장치 간 복잡한 트래픽 라우팅, 메모리 풀링 및 동적 용량 할당 제공 |

#### 한줄 요약

- 다중 호스트가 스위치 패브릭을 거쳐 3대 프로토콜 조합에 따라 분류된 장치들과 통신하며 유연한 확장 생태계를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타입 3 장치(Type 3 Device)**: 입출력 및 메모리 프로토콜만을 탑재하여 호스트 시스템에 대규모 확장 메모리 풀을 전담 제공하는 장치이다.
- **로드 완료(Load Completion)**: 프로세서가 발송한 읽기 기계어 명령이 프로토콜을 거쳐 확장 장치의 데이터를 레지스터로 성공적으로 복귀시킨 상태이다.

</details>

```text
[ 호스트 중앙처리장치 메모리 읽기 쓰기 요청 발생 ]
                         │
                         ▼
           [ 1. 주소 및 프로토콜 판정 ]
                         │
                         ▼
             [ 2. 프로토콜 동적 다중화 ]
             ├─ 제어 설정 ──> 입출력 프로토콜
             ├─ 가속기 캐시 ──> 캐시 프로토콜
             └─ 메모리 접근 ──> 메모리 프로토콜
                         │
                         ▼
             [ 3. 물리 계층 및 스위치 전송 ]
                         │
                         ▼
             [ 4. 확장 장치 메모리 접근 ]
                         │
                         ▼
             [ 5. 응답 반환 및 로드 완료 ]
```

### 동작 원리

1. 주소 및 프로토콜 판정: 요청된 주소와 종류를 분석하여 사용할 프로토콜을 결정함.
2. 프로토콜 다중화: 선택된 논리 프로토콜 패킷을 단일 물리 링크에 효율적으로 다중화함.
3. 계층 및 스위치 전송: 물리 계층과 패브릭 스위치를 거쳐 대상 장치 포트까지 패킷을 라우팅함.
4. 장치 메모리 접근: 분기된 메모리 프로토콜 요청으로 **타입 3 장치**의 메모리에 직접 접근함.
5. 응답 및 로드 완료: 인출된 데이터를 호스트로 반환하여 최종적인 **로드 완료** 상태를 달성함.

#### 한줄 요약

- 주소를 해석하여 프로토콜을 결정하고, 물리 링크 다중화 및 스위치 라우팅을 거쳐 확장 장치의 메모리를 읽어온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **타입 1 장치(Type 1 Device)**: 호스트 메모리를 캐시로 사용하는 지능형 네트워크 카드 등의 장치로 입출력 및 캐시 프로토콜을 조합하여 사용한다.
- **타입 2 장치(Type 2 Device)**: 자신의 내장 메모리와 호스트 메모리를 상호 일관되게 공유하는 연산 가속기로 3대 프로토콜을 모두 사용한다.
- **타입 3 장치(Type 3 Device)**: 자체 연산 없이 호스트의 시스템 용량 확장과 메모리 풀링만을 전담하는 전용 메모리 확장기이다.

</details>

| 비교 항목 | 타입 1 장치 | 타입 2 장치 | 타입 3 장치 |
|:---|:---|:---|:---|
| 프로토콜 조합 구성 | **입출력 프로토콜** 및 **캐시 프로토콜** 결합 | **입출력**, **캐시** 및 **메모리 프로토콜** 전체 결합 | **입출력 프로토콜** 및 **메모리 프로토콜** 결합 |
| 장치 대표 역할 | 호스트 시스템 메모리를 보조 캐시로 사용하는 특수 장치 | 장치 전용 메모리와 호스트 메모리를 상호 동등하게 공유하는 거대 가속기 | 추가적인 연산 기능 없이 오직 메모리 확장만을 전담하는 거대 메모리 기판 |
| 핵심 유스케이스 활용 | 호스트 메모리에 대한 초저지연 캐싱 및 네트워킹 연산 가속 | 호스트와 텐서 가속기 간의 고속 상호 메모리 공유 및 거대 모델 훈련 가속 | 메인 메모리 물리적 용량 확장 및 클라우드 센터 수준의 동적 **메모리 풀링** |
| 논리 주소 매핑 특성 | 호스트 주소 공간 인출 중심의 단방향 캐시 매핑 우선 | 호스트 공간과 가속기 공간 간의 양방향 일관성 접근 중심 매핑 우선 | 호스트의 확장 메모리 노드 주소 공간으로의 투명한 직접 매핑 중심 |

#### 한줄 요약

- 지능형 네트워크 카드(타입 1), 텐서 연산 가속기(타입 2), 거대 메모리 확장기(타입 3)로 역할을 세분화하여 프로토콜을 조합한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 온도(Data Temperature)**: 잦은 참조가 일어나는 뜨거운 데이터는 로컬 메모리에, 참조 빈도가 적은 차가운 데이터는 확장 메모리에 배치하는 분류 지표이다.
- **메모리 계층화(Memory Tiering)**: 운영체제가 로컬 메모리와 확장 메모리 간 페이지를 참조 빈도에 따라 자동 이관 및 배치하는 성능 튜닝 기술이다.
- **가상 채널(Virtual Channel)**: 전송 시 패킷 간 상호 자원 대기로 인한 교착 상태를 피하기 위해 물리 계층 내부에 논리 버퍼를 완전히 분리 할당하는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 확장 메모리의 물리적 접근 지연이 로컬 메모리보다 느려 발생하는 성능 하락 | 운영체제 수준의 **메모리 계층화** 도입 및 **데이터 온도** 기반 자동 이관 스케줄링 | 뜨거운 데이터의 국소성 유지로 확장 지연 오버헤드 최소화 보장 |
| 프로토콜 패킷 간 상호 자원 대기로 인한 치명적인 프로토콜 시스템 교착 상태 | 물리 계층 상의 **가상 채널** 버퍼 독립 할당 및 완벽한 분리 전송 구현 | 다중화 전송 중 트랜잭션 교착 상태 완벽 방지 및 처리량 보장 |
| 다중 호스트 공유 시 스위치 라우팅 병목으로 인한 심각한 패브릭 대경합 | 패브릭 관리자를 통한 정밀한 트래픽 대역폭 제어 및 품질 서비스 설정 도입 | 갑작스러운 꼬리 지연시간 상승 억제 및 안정적 대역폭 제공 보장 |
| 모듈의 물리적 탈착 및 하드웨어 오류 시 호스트 운영체제 전체 커널의 붕괴 | 고신뢰성 트랩 예외 처리 적용 및 물리적 핫플러그 기반 엄격한 장애 격리 가동 | 신속한 노드 격리 조치를 통한 중단 없는 클라우드 서비스 고가용성 유지 |

#### 한줄 요약

- 메모리 계층화로 성능 지연을 숨기고, 가상 채널 분리로 교착을 막으며, 관리자 제어로 안정적인 대역폭 품질을 사수한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **아키텍처 도입 결정 기준(Architecture Decision Criteria)**: 데이터센터의 메모리 용량 파편화율, 가속기 간 일관성 공유 요구, 메모리 풀링의 투자 대비 효과를 대조하여 인프라 도입을 결정하는 프레임워크이다.

</details>

- 단순 용량 부족에는 **타입 3 확장기**, 노드 간 공유 활용률이 낮으면 **스위치 풀링**을 도입함

#### 한줄 요약

- 도입 목표가 단순 용량 증설인지 자원의 동적 분배인지를 판가름하여 확장 장치와 스위치 장착 수준을 면밀히 결정해야 한다.
