## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 기존 PCIe 5.0/6.0 물리 계층 기반 상에서 호스트 CPU와 GPU, SmartNIC, CXL 메모리 확장기 간의 하드웨어 캐시 일관성(Cache Coherency) 및 저지연 Memory Load/Store 접근을 보장하는 차세대 오픈 인터커넥트 규격.
- **분리 주소 공간(Disjoint Address Space)**: 기존 PCIe 기반 가속기 장치가 호스트 메인 메모리와 격리된 독자 주소 공간을 가짐으로써 발생하던 비효율적 DMA 데이터 복사 및 오버헤드 구조.
- **메모리 풀링(Memory Pooling)**: 서버 랙(Rack) 내의 대용량 CXL DRAM 메모리를 중앙 공유 풀(Pool)로 구축하고, 각 서버 노드가 CXL 스위치를 통해 필요 용량을 동적 할당받아 공유하는 아키텍처.

</details>

- 정의/개념: PCIe 물리 계층 위에서 3가지 프로토콜(CXL.io, CXL.cache, CXL.mem)을 통해 호스트 프로세서와 가속기/메모리 장치 간 **하드웨어 캐시 일관성** 및 메모리 팽창을 지원하는 오픈 인터커넥트 아키텍처 **CXL(Compute Express Link)**.
- 배경/필요성: 기존 **분리 주소 공간** 환경의 심각한 DMA 데이터 복사 오버헤드와 CPU 소켓 메모리 슬롯 개수 물리적 한계를 극복하고, 클라우드 센터의 **메모리 풀링**을 달성하기 위해 필수 도입.

#### 한줄 요약
- PCIe 물리 층 상에서 CXL.io, CXL.cache, CXL.mem 프로토콜을 프로토콜 다중화하여, 캐시 일관성 유지 및 테라바이트 급 메모리 동적 확장/풀링을 지원하는 차세대 인터커넥트.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: 기존 PCIe 5.0/6.0 프로토콜과 100% 호환되어 CXL 장치 열거(Enumeration), 비일관 I/O, DMA 및 디바이스 설정을 전담하는 기본 프로토콜.
- **CXL.cache**: 가속기(GPU/NPU) 장치가 호스트 CPU의 메인 메모리를 저지연으로 직접 접근하고 일관성 캐싱할 수 있도록 지원하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 CXL Type-3 확장 메모리 칩을 일반 DRAM처럼 direct `Load/Store` 주소 공간으로 인식하여 억세스하게 만드는 프로토콜.
- **프로토콜 다중화(Protocol Multiplexing)**: 단일 PCIe 5.0/6.0 물리 PHY 링크 상에서 CXL.io, CXL.cache, CXL.mem 패킷을 시간 분할 다중화(TDM)하여 병렬 전송하는 하드웨어 기술.

</details>

- 단일 PCIe 물리 PHY 상에서 **CXL.io**, **CXL.cache**, **CXL.mem** 3종 프로토콜의 **프로토콜 다중화** 구동.
- **CXL.mem** 프로토콜을 통해 소켓 한계를 넘어서는 테라바이트(TB) 급 확장 DRAM 메모리를 일반 `Load/Store` 메모리로 투명하게 할당.
- 장치 유형에 맞는 **하드웨어 일관성**과 Load•Store 접근으로 명시적 복사 감소.

#### 한줄 요약
- 3대 전용 프로토콜 다중화, 하드웨어 캐시 일관성 제공, Load/Store 기반 CXL 메모리 용량 확장 및 동적 풀링을 지원함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL 루트 포트(CXL Root Port)**: CPU 소켓 내부에 집적되어 CXL 패브릭 트랜잭션을 발송 및 수신하는 호스트 측 최상위 포트.
- **CXL 스위치(CXL Switch)**: CXL 2.0/3.0 규격에서 멀티 호스트(Multi-Host)와 다수 CXL Type-3 메모리 장치 사이를 크로스바 스위칭해 주는 인터커넥트 스위치.
- **CXL 패브릭(CXL Fabric)**: CXL 스위치와 패브릭 관리자(Fabric Manager)를 통해 랙 전체의 메모리를 주소 공간에 동적 할당 및 분해하는 메모리 메쉬 네트워크.

</details>

```text
[ Compute Express Link (CXL) Multi-Host Architecture ]
┌─────────────────────────┐         ┌─────────────────────────┐
│ Host CPU 1 (CXL Root)   │         │ Host CPU 2 (CXL Root)   │
└────────────┬────────────┘         └────────────┬────────────┘
             │ (CXL.io / CXL.cache / CXL.mem)    │
             └──────────────────┬────────────────┘
                                │
                    [ CXL Switch / Fabric ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
 [ Type-1 Device ]       [ Type-2 Device ]       [ Type-3 Device ]
 (SmartNIC / DPU)        (GPU / NPU Accelerator) (CXL Memory Expander)
 (CXL.io + CXL.cache)    (CXL.io+.cache+.mem)    (CXL.io + CXL.mem)
```

| 구성요소 | 책임 |
|:---|:---|
| CXL.io | **장치 검색•설정•I/O** 제공 |
| CXL.cache | 장치의 **호스트 메모리 일관 캐싱** 지원 |
| CXL.mem | 호스트의 **장치 메모리 Load•Store** 지원 |
| CXL Switch•Fabric | **라우팅•풀링•동적 할당** 제공 |

#### 한줄 요약
- CXL Root Port, CXL Switch/Fabric, 3대 Protocol Engine 및 Type-1/2/3 Device 분류 체계로 탑재됨.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타입 3 장치(Type 3 Device / CXL Memory Expander)**: CXL.io 및 CXL.mem 프로토콜만을 탑재하여 호스트에 거대 확장 DRAM 메모리를 제공하는 메모리 익스팬더 칩셋.
- **로드 완료(Load Completion)**: CPU가 발송한 `Load` 기계어 파이프라인 명령이 CXL.mem 프로토콜을 거쳐 CXL 메모리 상의 데이터를 읽어 CPU 레지스터에 성공적으로 복귀된 상태.

</details>

```text
[ Host CPU Load/Store Instruction to CXL Address Space ]
                         │
                         ▼
        [ 1. 주소•프로토콜 판정 ]
                         │
                         ▼
        [ 2. 프로토콜 다중화 ]
        ├─ Device Reg / Config  ──> CXL.io  Protocol
        ├─ Accelerator Cacheing ──> CXL.cache Protocol
        └─ Memory Load / Store  ──> CXL.mem Protocol
                         │
                         ▼
        [ 3. PHY•Switch 전송 ]
                         │
                         ▼
        [ 4. Type-3 메모리 접근 ]
                         │
                         ▼
        [ 5. 응답•Load 완료 ]
```

### 동작 원리

1. **주소•프로토콜 판정**: 주소와 요청 종류로 사용할 CXL 프로토콜을 정함.
2. **프로토콜 다중화**: 논리 프로토콜 패킷을 링크에 다중화함.
3. **PHY•Switch 전송**: 대상 포트까지 패킷을 라우팅함.
4. **Type-3 메모리 접근**: CXL.mem 요청으로 장치 DRAM에 접근함.
5. **응답•Load 완료**: 데이터를 호스트에 반환하여 요청을 완료함.

#### 한줄 요약
- Address Check -> Protocol Selection(io/cache/mem) -> PHY Multiplexing -> Switch Routing -> Type-3 DRAM Read & Load Completion 순으로 동작함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **타입 1 장치 (Type 1 Device)**: CXL.io 및 CXL.cache 프로토콜을 사용하여 호스트 메모리를 저지연 캐싱하는 SmartNIC, PGAS 가속기.
- **타입 2 장치 (Type 2 Device)**: CXL.io, CXL.cache, CXL.mem 프로토콜 전체를 사용하여 내장 메모리와 호스트 메모리를 상호 일관 공유하는 GPU, NPU.
- **타입 3 장치 (Type 3 Device)**: CXL.io 및 CXL.mem 프로토콜만을 가동하여 시스템 DRAM 확장 및 풀링을 전담하는 CXL Memory Expander.

</details>

| CXL 장치 분류 | Type-1 Device | Type-2 Device | Type-3 Device |
|:---|:---|:---|:---|
| **적용 프로토콜** | **CXL.io + CXL.cache** | **CXL.io + CXL.cache + CXL.mem** | **CXL.io + CXL.mem** |
| **대표 역할**| 호스트 메모리를 캐시하는 가속기 | 장치 메모리와 호스트 메모리를 쓰는 가속기 | **CXL Memory Expander** |
| **핵심 유스케이스** | 호스트 메모리 저지연 캐싱 | 호스트-가속기 간 고속 캐시/메모리 공유 | 메인 메모리 용량 확장 및 **메모리 풀링** |
| **주소 매핑 특성** | 호스트 주소 공간 인출 중심 | 호스트-가속기 양방향 억세스 중심 | 호스트의 NUMA 노드2 확장 매핑 중심 |

#### 한줄 요약
- Type-1(SmartNIC, io+cache), Type-2(GPU/NPU, io+cache+mem), Type-3(Memory Expander, io+mem)의 3가지 규격 장치로 분류됨.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 온도 (Data Temperature)**: 자주 참조되는 Hot Data는 저지연 로컬 DRAM에 배치하고, 참조 빈도가 적은 Cold Data는 CXL 확장 메모리에 배치하는 계층화 지표.
- **메모리 계층화 (Memory Tiering)**: Linux 커널 NUMA 티어링(AutoTiering/CXL-Tiering)을 연동하여 로컬 DRAM(Tier 0)과 CXL 메모리(Tier 1) 간 페이지를 자동 배치하는 기술.
- **가상 채널 (Virtual Channel / VC)**: CXL 프로토콜 전송 시 CXL.cache 패킷과 CXL.mem 패킷이 동일 버퍼 교착 상태(Deadlock)에 빠지지 않도록 버퍼를 분리 할당하는 기법.

</details>

| 문제 및 병목 원인 | 실무적 대책 및 해결 방안 | 기대 효과 |
|:---|:---|:---|
| CXL 메모리 억세스 지연(150ns)이 로컬 DRAM(60ns)보다 느려 성능 하락 | Linux **메모리 계층화** 및 **Data Temp** 자동 이관 | Hot Data 로컬 유지로 성능 감소 극소화 |
| CXL.cache와 CXL.mem 패킷 간 상호 자원 대기로 인한 **프로토콜 교착** | PCIe PHY 상의 **가상 채널** 독립 분리 | 트랜잭션 교착 상태(Deadlock) 완벽 방지 |
| 멀티 호스트 공유 시 CXL 스위치 병목으로 **패브릭 경합** | **CXL 3.0/3.1 Fabric Manager** 대역폭 제어 및 QoS 설정 | 꼬리 지연시간(Tail Latency) 조율 및 안정적 대역폭 제공 |
| CXL 모듈 물리 탈착 및 오류 시 호스트 OS 전체 Kernel Panic | CXL **RAS(Reliability, Availability, Serviceability)** 트랩 적용 | Hot-Plug 및 장애 발생 노드 격리로 고가용성 유지 |

#### 한줄 요약
- Memory Tiering(Hot/Cold 분리), Virtual Channel 설정(Deadlock 방지), Fabric Manager QoS 및 CXL RAS 고가용성 기법을 적용함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL 아키텍처 선택 기준(CXL Decision Criteria)**: 데이터센터의 서버 랙 메모리 파편화율, LLM 가속기 간 캐시 공유 요구 및 메모리 풀링 ROI를 대조하여 CXL 2.0/3.0 스위치 패브릭을 도입하는 결정 프레임워크.

</details>

- 용량 부족이면 **Type-3 확장**, 공유 활용률이 낮으면 **Switch Pooling** 적용.

#### 한줄 요약
- 지연•용량•풀링 이득을 기준으로 CXL 장치와 Tiering 정책을 결정함.
