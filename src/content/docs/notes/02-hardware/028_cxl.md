## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 고속 PCIe 물리 계층을 기반으로 호스트 프로세서, 가속기, 메모리 확장 장치 간에 I/O, 캐시 일관성, 메모리 공유 의미론을 단일 링크로 다중화하여 제공하는 차세대 개방형 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트 CPU와 주변 장치가 독립된 주소 공간을 사용하여 데이터 교환 시 명시적인 DMA 복사 오버헤드가 발생하는 기존 시스템 구조.
- **메모리 풀링(Memory Pooling)**: 분산된 CXL 메모리 자원을 단일 공유 풀로 구성하여 여러 서버가 필요에 따라 동적으로 메모리를 할당받고 반납하는 자원 가상화 기술.

</details>

- 정의/개념: PCIe 물리 계층 위에서 I/O 통신, 하드웨어 캐시 일관성 유지, 메모리 공유 의미론을 단일 패브릭으로 다중화하여 호스트와 가속기 간 고속 연결을 지원하는 **차세대 개방형 인터커넥트 표준**
- 배경/필요성: 기존 PCIe 인터페이스의 분리 주소 공간과 명시적 DMA 복사 오버헤드로 인한 **캐시 비일관성 및 메모리 파편화** 한계를 극복하고, AI 및 클라우드 데이터센터의 메모리 풀링 요구를 충족하기 위해 도입

#### 한줄 요약
- CXL은 PCIe 물리 링크 위에서 I/O, 캐시 일관성, 메모리 확장을 단일 인터페이스로 융합하여 차세대 메모리 풀링과 가속기 협업을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: PCIe 표준 기반의 장치 검색, 구성 레지스터 설정 및 비일관적 대용량 DMA 데이터 전송을 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기(GPU/FPGA)가 호스트 CPU의 시스템 메모리를 초저지연으로 직접 캐싱하고 하드웨어적으로 일관성을 유지할 수 있도록 지원하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 CXL 확장 장치에 장착된 메모리를 표준 로드/스토어(Load/Store) 명령어로 직접 접근할 수 있도록 주소 공간을 확장하는 프로토콜.

</details>

- 단일 물리 링크 상에서 **CXL.io, CXL.cache, CXL.mem**의 3대 독립 프로토콜 동적 다중화 지원
- CPU 물리 주소 공간에 직접 매핑되어 로드/스토어 방식으로 동작하는 **초저지연 메모리 확장 및 풀링** 실현
- 호스트 프로세서와 이종 가속기 간의 **하드웨어 수준 캐시 일관성**을 보장하여 소프트웨어 복사 오버헤드 원천 제거

#### 한줄 요약
- CXL은 io, cache, mem 3대 프로토콜을 통해 하드웨어 캐시 일관성과 동적 메모리 확장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL 루트 포트(CXL Root Port)**: 호스트 CPU 다이 내부에 직접 통합되어 CXL.io, CXL.cache, CXL.mem 패킷을 인코딩/디코딩하는 최상위 인터페이스.
- **CXL 스위치/패브릭(CXL Switch/Fabric)**: 다수의 호스트 CPU와 다양한 CXL 엔드포인트 장치 간의 트래픽을 크로스바 토폴로지로 라우팅하여 대규모 메모리 풀링을 중계하는 스위치.

</details>

```text
+-------------------------------------------------------------+
|                 호스트 프로세서 (Host CPU)                  |
|  +-----------------------+       +-----------------------+  |
|  |     CPU Core / LLC    | <---> |    CXL 루트 포트      |  |
|  +-----------------------+       +-----------------------+  |
+-------------------------------------------------------------+
                               |
                               | PCIe 5.0/6.0 물리 링크 (PHY)
                               v
+-------------------------------------------------------------+
|                CXL 스위치 패브릭 (CXL Fabric Switch)        |
+-------------------------------------------------------------+
         |                     |                     |
         v                     v                     v
+-----------------+   +-----------------+   +-----------------+
|  Type-1 장치    |   |  Type-2 장치    |   |  Type-3 장치    |
| (SmartNIC/DPU)  |   | (GPU/NPU 가속기)|   | (메모리 확장기) |
| +-------------+ |   | +-------------+ |   | +-------------+ |
| | CXL.io      | |   | | CXL.io      | |   | | CXL.io      | |
| | CXL.cache   | |   | | CXL.cache   | |   | | CXL.mem     | |
| +-------------+ |   | | CXL.mem     | |   | +-------------+ |
|                 |   | +-------------+ |   | (DRAM 풀링)   |
+-----------------+   +-----------------+   +-----------------+
```

선의 의미: 실선 화살표는 CXL 루트 포트에서 스위치 패브릭을 경유하여 각 장치 유형별 프로토콜(io/cache/mem)로 분기하는 고속 인터커넥트 패킷 전송 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| **CXL 루트 포트** | 호스트 CPU 내부에서 3대 프로토콜 패킷 인코딩 및 하드웨어 **일관성 제어** |
| **CXL 스위치 패브릭** | 다중 호스트와 엔드포인트 간 크로스바 라우팅 및 **동적 메모리 풀링** 중계 |
| **Type-1 장치** | 스마트NIC/DPU로서 **CXL.cache** 프로토콜 기반 호스트 메모리 직접 캐싱 |
| **Type-2 장치** | GPU/FPGA 가속기로서 **CXL.cache 및 CXL.mem**을 통한 양방향 메모리 공유 |
| **Type-3 장치** | 순수 메모리 확장기로서 **CXL.mem** 프로토콜 기반 호스트 주소 공간 확장 |

#### 한줄 요약
- Type-1·2는 가속기가 호스트 메모리를 직접 캐싱해 장치 메모리로 데이터를 복사하던 단계를 없애고, Type-3는 호스트 주소 공간에 편입돼 소켓에 물려야 했던 DRAM 증설을 대신하며, 스위치 패브릭이 그 장치를 한 호스트 전속에서 풀로 끌어낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 메모리 읽기**: CPU가 CXL 영역 주소로 로드 명령을 발행하면 IMC가 CXL.mem 읽기 요청 패킷을 생성하여 외부 CXL 메모리에서 데이터를 인출해 오는 동작.

</details>

```text
+-------------------------------------------------------------+
|        호스트 CPU 코어 메모리 Load / Store 명령어 실행       |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     1. 주소 디코딩 및 판정    |
               +-------------------------------+
                      |                 |
             [로컬 DRAM 영역]           | [CXL 매핑 영역]
                      |                 v
                      | +-------------------------------+
                      | | 2. CXL.mem 요청 패킷 생성     |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 3. 루트 포트 및 PHY 링크 전송 |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 4. Type-3 DRAM 데이터 인출    |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 5. CXL.mem 응답 반환 및 로드  |
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 온보드 DDR 직접 인출  |               |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
|          CPU 레지스터로 데이터 적재 및 파이프라인 진행       |
+-------------------------------------------------------------+
```

분기 결과: **로컬 DRAM** 접근 시 수십 ns의 초저지연으로 즉시 반환되나, **CXL 확장 메모리** 접근 시 PCIe 물리 계층 패킷화로 인해 약 150~200ns 수준의 통신 지연이 추가로 발생함

**동작 원리**

1. **주소 디코딩 및 영역 판정**: 호스트 통합 메모리 컨트롤러(IMC)가 CPU 코어의 물리 주소를 디코딩하여 로컬 채널 또는 CXL 주소 공간 여부를 판별함
2. **CXL.mem 읽기 요청 패킷 생성**: CXL 영역으로 매핑된 주소인 경우 로컬 버스 대신 CXL.mem 프로토콜 규격의 저지연 요청 패킷을 생성함
3. **루트 포트 및 고속 PHY 전송**: 생성된 패킷이 호스트 CXL 루트 포트를 통해 PCIe 물리 링크로 직렬화되어 스위치 또는 Type-3 장치로 전송됨
4. **Type-3 로컬 메모리 인출**: CXL 메모리 컨트롤러가 패킷을 디코딩하여 온보드 장착된 표준 DDR5 DRAM 어레이의 지정 행/열 데이터를 고속 인출함
5. **응답 패킷 전송 및 CPU 적재**: 인출된 64바이트 캐시 라인 데이터가 CXL.mem 응답 패킷에 실려 호스트 루트 포트로 역방향 전송되고 CPU 코어 레지스터로 최종 반환됨

#### 한줄 요약
- CPU가 주소를 발행하면 IMC가 판별하여 로컬 메모리는 직접 읽고, CXL 메모리는 CXL.mem 패킷으로 인출하여 반환한다.

## Ⅴ. 종류 및 비교

| 인터커넥트 기술 | CXL (Compute Express Link) | PCIe (PCI Express) | 독점 인터커넥트 (NVLink 등) |
|:---|:---|:---|:---|
| 적용 기준 | 이종 장치 간 메모리 공유 및 하드웨어 캐시 일관성 요구 시 | 표준 입출력 장치 연결 및 단순 비일관 대용량 DMA 요구 시 | 동일 제조사 가속기 간 극대화된 대역폭 공유 요구 시 |
| 핵심 특징 | **캐시 일관성·로드/스토어** 의미론 및 3대 프로토콜 다중화 | 패킷 기반 계층형 **DMA 입출력** 표준 버스 | 전용 초고속 시리얼 링크 및 **독점 프로토콜** |
| 한계 | 물리 링크 패킷화에 따른 미세 지연 및 스위치 관리 복잡도 | 메모리 공유 의미론 및 **하드웨어 일관성 부재** | 특정 벤더 하드웨어 **종속성** 및 범용성 결여 |

#### 한줄 요약
- PCIe는 비일관 I/O에 그치고 독점 링크는 폐쇄적인 반면, CXL은 개방형 표준으로 캐시 일관성과 메모리 확장을 모두 실현한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 계층화(Memory Tiering)**: 접근 빈도가 높은 핫 데이터는 로컬 DRAM(Tier 0)에, 콜드 데이터는 CXL 확장 메모리(Tier 1)에 배치하는 OS 계층화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 물리 링크 경유에 따른 CXL 메모리 접근 지연 증가 | OS 기반 **NUMA 메모리 계층화(Tiering)** 적용 | 핫 데이터 로컬 DRAM 배치로 실효 메모리 지연 최소화 |
| 다중 호스트 공유 시 패브릭 링크 대역폭 경합 발생 | **CXL 스위치 QoS** 및 가상 계층 격리 | 호스트 간 트래픽 간섭 차단 및 공정 대역폭 보장 |
| 원격 CXL 메모리 모듈 링크 단절 및 물리 장애 발생 | **메모리 포이즈닝(Poisoning)** 및 비동기 페이지 마이그레이션 | 시스템 전체 다운 방지 및 무중단 고가용성 유지 |

#### 한줄 요약
- 실무에서는 메모리 계층화로 지연을 완화하고, QoS로 대역폭 경합을 통제하며, 장애 격리로 시스템 신뢰성을 확보한다.

- 

#### 한줄 요약
- CXL은 개방형 표준 기반으로 하드웨어 캐시 일관성과 메모리 풀링을 완성하는 차세대 데이터센터 인터커넥트의 핵심이다.
