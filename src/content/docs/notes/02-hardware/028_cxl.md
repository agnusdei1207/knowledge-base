## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: PCIe 위에서 캐시 일관성과 메모리 공유를 제공하는 규격.
- **PCIe(Peripheral Component Interconnect Express)**: 고속 직렬 장치 인터커넥트.
- **분리 주소 공간(Disjoint Address Space)**: 호스트와 장치가 각자 주소 공간을 가져 복사와 소프트웨어 동기화가 필요한 구조.

</details>

- 정의/개념: **PCIe** 물리 링크에서 I/O·캐시·메모리 프로토콜을 제공하는 **CXL** 규격
- 배경/필요성: 가속기와 호스트 간 **분리 주소 공간** 구조에서 과도한 데이터 복사 오버헤드와 메모리 용량 파편화 발생

#### 한줄 요약

- CXL은 호스트와 장치 사이에 일관된 캐시·메모리 접근을 제공해 데이터 복사와 메모리 중복을 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **CXL.io**: 장치 설정과 비일관 I/O를 지원하는 프로토콜.
- **CXL.cache**: 장치의 호스트 메모리 일관 캐시를 지원하는 프로토콜.
- **CXL.mem**: 호스트가 장치 메모리를 일반 로드•스토어로 접근하게 하는 프로토콜.
- **프로토콜 다중화(Protocol Multiplexing)**: 하나의 PCIe 물리 링크에 I/O•캐시•메모리 요청을 구분해 함께 전달하는 방식.
- **하드웨어 일관성(Hardware Coherence)**: 장치와 호스트의 캐시 사본을 프로토콜이 자동으로 최신 상태로 맞추는 성질.

</details>

- 한 물리 링크에서 **CXL.io**·**CXL.cache**·**CXL.mem** 요청 **프로토콜 다중화**
- **CXL.mem** 기반 장치 메모리의 로드·스토어 접근과 메모리 계층화
- **하드웨어 일관성** 기반의 복사 없는 메모리 공유

#### 한줄 요약

- CXL은 프로토콜 다중화로 한 물리 링크에서 I/O·캐시·메모리 요청을 구분해 전달하고, 확장 메모리는 지연이 다른 별도 계층으로 관리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **루트 포트(Root Port)**: 프로세서에서 CXL 장치 경로가 시작되는 호스트 측 연결점.
- **CXL 스위치(CXL Switch)**: 요청을 대상 CXL 장치로 분기하는 구성요소.
- **CXL 패브릭(CXL Fabric)**: 여러 호스트와 장치를 연결하는 경로망.
- **메모리 풀링(Memory Pooling)**: 여러 호스트가 공용 장치 메모리에서 필요한 용량을 동적으로 할당받는 방식.

</details>

```text
[CXL 호스트]
      |
CXL 패브릭 경계
      |
[CXL 루트 포트] -- [CXL 스위치] -- [CXL 장치 집합]
```

선의 의미: 호스트가 루트 포트로 패브릭에 접속하고 스위치가 장치 집합을 공유 연결하는 정적 경계•네트워크 관계.

| 구성요소 | 책임 |
|:---|:---|
| CXL 호스트 | 프로세서 요청과 **하드웨어 일관성** 관리 |
| CXL 루트 포트 | 호스트•장치 경로 시작 |
| CXL 스위치 | 대상 장치 요청 분기와 공유 경로 제공 |
| CXL 장치 집합 | 가속기 캐시•확장 메모리 제공 |

#### 한줄 요약

- 루트 포트와 스위치가 호스트 요청을 일관성을 유지한 채 CXL 장치로 전달한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **타입 3 장치(Type 3 Device)**: CXL.io와 CXL.mem으로 확장 메모리를 제공하는 장치.
- **직결 경로(Direct Path)**: 루트 포트에서 장치로 직접 요청을 전달하는 경로.
- **스위치 경로(Switched Path)**: 패브릭 스위치를 거쳐 요청을 전달하는 경로.
- **로드 완료(Load Completion)**: 장치 메모리에서 읽은 데이터가 CXL.mem 응답으로 호스트 CPU에 반환된 상태.

</details>

```text
                    [호스트•장치 요청]
                             |
                 1. 요청 목적•프로토콜 판정
                    /          |          \
             [장치 설정] [장치의 호스트 캐시] [장치 메모리]
                 |             |              |
              [CXL.io]     [CXL.cache]     [CXL.mem]
                 \             |              /
                  2. PCIe PHY 링크 다중화
                             |
                   3. 직결•스위치 경로 선택
                             |
                  4. 대상 장치•메모리 처리
                             |
                 [일관성 응답•로드 완료]
```

### 동작 원리

1. **요청·프로토콜 판정**: 장치 설정, 호스트 메모리 캐시, 장치 메모리 접근을 구분해 CXL 프로토콜 선택.
2. **물리 링크 다중화**: **CXL.io**·**CXL.cache**·**CXL.mem** 패킷을 하나의 PCIe 기반 물리 링크로 전송.
3. **대상 경로 라우팅**: 주소와 장치 매핑에 따라 **직결 경로** 또는 **스위치 경로**로 요청 전달.
4. **장치·메모리 처리**: **타입 3 장치**의 DRAM이 로드·스토어 수행하거나 대상 장치가 일관성 요청을 처리하고 응답 데이터를 CPU에 반환.

#### 한줄 요약

- 직결 경로는 스위치 단계를 줄여 지연이 짧고, 스위치 경로는 추가 지연을 부담하는 대신 여러 장치의 연결과 메모리 풀링을 지원한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **메모리 매핑 입출력(Memory-Mapped I/O, MMIO)**: 메모리 주소로 장치 레지스터에 접근하는 방식.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치가 CPU 개입 없이 메모리와 직접 전송하는 방식.
- **로드•스토어 접근(Load/Store Access)**: 별도 전송 API 대신 일반 메모리 명령으로 장치 메모리를 읽고 쓰는 방식.
- **소프트웨어 동기화(Software Synchronization)**: 공유 데이터의 최신값과 접근 순서를 호스트와 장치 소프트웨어가 명시적으로 맞추는 처리.

</details>

| 인터커넥트 규격 | CXL | PCIe |
|:---|:---|:---|
| 적용 기준 | **하드웨어 일관성** 필요한 캐시•메모리 접근 | 장치 I/O와 **DMA** 전송으로 충분할 때 |
| 핵심 특징 | **하드웨어 일관성** 기반 **로드•스토어 접근** | **MMIO**•**DMA** 기반 비일관 전송 |
| 한계 | 링크 경유 접근 지연과 상호운용 검증 | 공유 데이터의 **소프트웨어 동기화** |

> 요약: CXL은 PCIe에 일관성 추가.

#### 한줄 요약

- 일반 PCIe는 MMIO·DMA 장치 전송에 적합하고, CXL은 일관된 캐시·메모리 접근과 메모리 용량 확장에 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **데이터 온도(Data Temperature)**: 최근 접근 빈도와 지연 민감도로 데이터를 로컬•확장 계층에 배치하는 기준.
- **패브릭 경합(Fabric Contention)**: 여러 호스트와 장치의 요청이 공유 링크와 스위치 큐에 몰리는 상태.
- **RAS(Reliability, Availability, Serviceability)**: 오류 탐지•격리•복구 능력.
- **상호운용성(Interoperability)**: 서로 다른 업체의 CXL 장치가 함께 동작하는 능력.
- **가상 채널(Virtual Channel)**: 패킷 종류별 버퍼와 흐름을 논리적으로 분리해 순환 자원 대기를 방지하는 전송 자원.
- **프로토콜 교착(Protocol Deadlock)**: 요청과 응답이 서로의 버퍼나 자원을 기다려 진행하지 못하는 상태.
- **장애 도메인 격리(Fault Domain Isolation)**: 링크나 장치의 오류가 다른 호스트·장치로 퍼지지 않도록 실패 범위를 나누는 설계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 로컬 DRAM보다 긴 CXL 메모리 접근 지연 | **데이터 온도**에 따라 로컬·CXL 계층 배치 | 지연 민감 데이터를 로컬에 유지해 응답 지연 완화 |
| 여러 호스트·장치 요청으로 **패브릭 경합** | 경로별 대역폭·큐 깊이 감시와 풀 할당량 제한 | 링크 혼잡 감소로 꼬리 지연 완화 |
| 요청·응답 버퍼가 서로를 기다려 **프로토콜 교착** | 패킷별 **가상 채널**과 자원 사용 순서 분리 | 순환 대기 제거로 장치 진행 보장 |
| 링크·스위치 장애와 구현 차이로 공유 메모리 접근 중단 | **장애 도메인 격리**와 **RAS**·**상호운용성** 검증 | 오류 전파 제한으로 서비스 지속성 확보 |

> 사례: **CXL.cache** 기반 호스트 메모리 공유

#### 한줄 요약

- CXL.cache로 데이터 복사를 줄이되 메모리 접근 지연, 패브릭 경합, 프로토콜 교착과 장애 범위를 함께 검증한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **CXL 메모리(CXL Memory)**: 로컬 DRAM보다 느리지만 공유•용량 확장을 제공하는 계층.
- **메모리 계층화(Memory Tiering)**: 지연과 용량이 다른 로컬 DRAM과 CXL 메모리를 별도 단계로 배치하는 방식.
- **링크 지연(Link Latency)**: CXL 프로토콜과 전송 경로를 거치며 로컬 DRAM보다 추가되는 접근 시간.
- **CXL 적용 기준**: 공유·용량 확장 이득과 링크 지연을 비교해 CXL 메모리 적용 여부를 정하는 기준.

</details>

- **CXL 적용 기준**에 따라 **CXL 메모리**의 공유•용량 이득이 **링크 지연**보다 크면 **메모리 계층화** 적용

#### 한줄 요약

- 용량 확장과 공유 이득이 링크 지연보다 클 때 CXL을 별도 메모리 계층으로 적용한다.
