## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 고속 PCIe 물리 계층을 기반으로 호스트 프로세서, 가속기, 메모리 확장 장치 간에 I/O, 캐시 일관성, 메모리 공유 의미론을 단일 링크로 다중화하여 제공하는 차세대 개방형 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트 CPU와 주변 장치가 독립된 주소 공간을 사용하여 데이터 교환 시 명시적인 DMA 복사 오버헤드가 발생하는 기존 시스템 구조.
- **메모리 풀링(Memory Pooling)**: 분산된 CXL 메모리 자원을 단일 공유 풀로 구성하여 여러 서버가 필요에 따라 동적으로 메모리를 할당받고 반납하는 자원 가상화 기술.

</details>

- 정의/개념: PCIe PHY에서 **CXL.io·cache·mem**을 다중화한 **CXL** 표준
- 배경/필요성: 기존 PCIe 인터페이스의 분리된 주소 공간과 DMA 기반 전송으로 인한 **캐시 비일관성 및 메모리 복사 오버헤드**, 서버 간 메모리 파편화 문제 해소 필요

#### 한줄 요약
- CXL은 PCIe 물리 링크 위에서 I/O, 캐시 일관성, 메모리 확장을 단일 인터페이스로 융합하여 차세대 메모리 풀링과 가속기 협업을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: PCIe 표준 기반의 장치 검색, 구성 레지스터 설정 및 비일관적 대용량 DMA 데이터 전송을 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기(GPU/FPGA)가 호스트 CPU의 시스템 메모리를 초저지연으로 직접 캐싱하고 하드웨어적으로 일관성을 유지할 수 있도록 지원하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 CXL 확장 장치에 장착된 메모리를 표준 로드/스토어(Load/Store) 명령어로 직접 접근할 수 있도록 주소 공간을 확장하는 프로토콜.

</details>

- 단일 링크에서 **CXL.io·cache·mem** 프로토콜 다중화
- **CXL.mem** 기반 주소 공간 확장과 **메모리 풀링**
- **CXL.cache** 기반 호스트·가속기 캐시 일관성

#### 한줄 요약
- CXL은 io, cache, mem 3대 프로토콜을 통해 하드웨어 캐시 일관성과 동적 메모리 확장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL 루트 포트(CXL Root Port)**: 호스트 CPU 다이 내부에 직접 통합되어 CXL.io, CXL.cache, CXL.mem 패킷을 인코딩/디코딩하는 최상위 인터페이스.
- **CXL 스위치/패브릭(CXL Switch/Fabric)**: 다수의 호스트 CPU와 다양한 CXL 엔드포인트 장치 간의 트래픽을 크로스바 토폴로지로 라우팅하여 대규모 메모리 풀링을 중계하는 스위치.

</details>

```text
[CXL 시스템 서브시스템]
├── [호스트 CPU 서버] (CXL 루트 포트 및 캐시 일관성 제어기)
├── [CXL 스위치 패브릭] (다중 호스트 간 메모리 풀링 라우팅)
└── [CXL 엔드포인트 장치]
    ├── [Type-1: 스마트 NIC/DPU] (CXL.io 및 CXL.cache 지원)
    ├── [Type-2: 가속기 GPU/NPU] (CXL.io, CXL.cache, CXL.mem 지원)
    └── [Type-3: 메모리 확장기] (CXL.io 및 CXL.mem 메모리 풀)
```

선/분기 의미: 트리 구조(`├──`, `└──`)는 CXL 시스템의 계층적 하드웨어 구성 및 장치 유형별 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| CXL 루트 포트 | 프로토콜 인코딩과 **일관성 제어** |
| CXL 스위치 패브릭 | 다중 호스트·장치의 **패킷 라우팅** |
| Type-1 장치 | **CXL.cache** 기반 호스트 메모리 캐싱 |
| Type-2 장치 | **CXL.cache·mem** 기반 양방향 공유 |
| Type-3 장치 | **CXL.mem** 기반 호스트 주소 공간 확장 |

#### 한줄 요약
- Type-1·2는 가속기가 호스트 메모리를 직접 캐싱해 장치 메모리로 데이터를 복사하던 단계를 없애고, Type-3는 호스트 주소 공간에 편입돼 소켓에 물려야 했던 DRAM 증설을 대신하며, 스위치 패브릭이 그 장치를 한 호스트 전속에서 풀로 끌어낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 메모리 읽기**: CPU가 CXL 영역 주소로 로드 명령을 발행하면 IMC가 CXL.mem 읽기 요청 패킷을 생성하여 외부 CXL 메모리에서 데이터를 인출해 오는 동작.

</details>

```text
[호스트 CPU 코어의 Load / Store 메모리 접근 명령 실행]
                          │
                          ▼
1. 주소 영역 판정
       ┌──────────────────┴──────────────────┐
 [ 로컬 DRAM 주소 영역 ]               [ CXL 확장 메모리 주소 영역 ]
       │                                     │
       ▼                                     ▼
[로컬 DDR 채널 직접 접근]              2. CXL.mem 읽기 요청 생성
       │                                     │
       │                                     ▼
       │                              3. 루트 포트·PCIe PHY 전송
       │                                     │
       │                                     ▼
       │                              4. Type-3 DRAM 데이터 인출
       │                                     │
       │                                     ▼
       │                              5. CXL.mem 응답 전송
       └──────────────────┬──────────────────┘
                          │
                          ▼
[CPU 코어로 데이터 반환 완료 및 투명 메모리 접근]
```

분기 결과: **로컬 DRAM**은 최단 지연(수십 ns)으로 완료되고, **CXL 메모리**는 전송 지연이 발생하나 주소 공간이 투명하게 확장됨

**동작 원리**

1. **주소 영역 판정**: 물리 주소로 로컬·CXL 영역 선택
2. **CXL.mem 읽기 요청 생성**: 확장 메모리 요청 패킷 구성
3. **루트 포트·PCIe PHY 전송**: Type-3 장치로 요청 전달
4. **Type-3 DRAM 데이터 인출**: 장치 메모리에서 데이터 조회
5. **CXL.mem 응답 전송**: 인출 데이터를 호스트로 반환

#### 한줄 요약
- CPU가 주소를 발행하면 IMC가 판별하여 로컬 메모리는 직접 읽고, CXL 메모리는 CXL.mem 패킷으로 인출하여 반환한다.

## Ⅴ. 종류 및 비교

| 인터커넥트 | CXL | PCIe | 독점 인터커넥트 |
|:---|:---|:---|:---|
| 적용 기준 | 메모리 공유·이종 가속 | 비일관 I/O 장치 | 동일 벤더 가속기 결합 |
| 핵심 특징 | **캐시 일관성·로드/스토어** | **DMA 기반 I/O** | 전용 장비 간 고속 공유 |
| 한계 | 링크 지연과 패브릭 관리 | 메모리 의미론·일관성 부재 | **독점 생태계** 종속 |

#### 한줄 요약
- PCIe는 비일관 I/O에 그치고 독점 링크는 폐쇄적인 반면, CXL은 개방형 표준으로 캐시 일관성과 메모리 확장을 모두 실현한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 계층화(Memory Tiering)**: 접근 빈도가 높은 핫 데이터는 로컬 DRAM(Tier 0)에, 콜드 데이터는 CXL 확장 메모리(Tier 1)에 배치하는 OS 계층화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 링크 경유 접근 지연 | OS 레벨 **메모리 계층화(Tiering)** 및 NUMA 가중치 설정 | 핫 데이터 로컬성 유지로 지연 단축 |
| 패브릭 대역폭 경합 | **CXL 스위치 QoS** 및 링크 어그리게이션 적용 | 대역폭 병목 해소 및 공정 분배 |
| 원격 메모리 장애 | **메모리 장애 격리(Poisoning)** 및 비동기 페이지 마이그레이션 | 무중단 **고가용성(HA)** 확보 |

#### 한줄 요약
- 실무에서는 메모리 계층화로 지연을 완화하고, QoS로 대역폭 경합을 통제하며, 장애 격리로 시스템 신뢰성을 확보한다.

## Ⅶ. 결론

- PCIe 5.0/6.0 물리 계층을 기반으로 캐시 일관성, 메모리 확장, 메모리 풀링을 단일 표준으로 통합한 **차세대 데이터센터 인터커넥트의 핵심 규격(CXL 2.0/3.0/3.1)**이며, 향후 **CXL 패브릭 스위치 기반의 컴포저블 인프라(Composable Disaggregated Infrastructure, CDI)**로 전면 확산 추세

#### 한줄 요약
- CXL은 개방형 표준 기반으로 하드웨어 캐시 일관성과 메모리 풀링을 완성하는 차세대 데이터센터 인터커넥트의 핵심이다.
