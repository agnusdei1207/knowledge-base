## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CXL(Compute Express Link)**: PCIe 기반 전기·물리 계층을 활용해 호스트와 가속기·메모리 장치 사이의 I/O, 캐시 일관성, 메모리 접근 의미론을 제공하는 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트와 디바이스 메모리가 분리되어 매번 DMA 복사 오버헤드가 발생하는 전통적 아키텍처.
- **메모리 풀링(Memory Pooling)**: CXL 패브릭과 관리 소프트웨어를 통해 메모리 자원을 호스트 요구에 맞게 할당·회수하는 구성 방식.

</details>

- 정의/개념: PCIe 물리 계층 기반으로 **캐시 일관성(CXL.cache)** 과 **메모리 공유(CXL.mem)** 를 지원하는 고속 개방형 인터커넥트 표준
- 배경/필요성: 호스트·가속기의 분리 주소 공간은 명시적 복사를 유발하고, 서버별 고정 메모리 배치는 **유휴 용량** 발생

#### 한줄 요약

- CXL은 PCIe 전기 계층 위에서 I/O·캐시 일관성·메모리 접근 의미론을 용도별로 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: 장치 열거, 탐색, 레지스터 설정 및 비일관적 DMA I/O를 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기가 호스트 메모리를 캐싱하면서 하드웨어 일관성을 유지하는 프로토콜.
- **CXL.mem**: 호스트가 CXL 장치에 연결된 메모리를 로드·스토어 의미론으로 접근하는 프로토콜. 실제 지연과 배치 정책은 로컬 DRAM과 다르다.

</details>

- 단일 링크에서 **CXL.io**와 용도별 **CXL.cache·CXL.mem** 의미론을 다중화해 전송
- **CXL.mem**으로 장치 연결 메모리를 호스트 주소 공간에 확장하고 패브릭 풀링 지원
- **하드웨어 캐시 일관성** 지원으로 명시적 데이터 복사 및 동기화 부담 완화

#### 한줄 요약

- CXL은 장치 역할에 따라 필요한 프로토콜을 조합하고, 스위치 패브릭으로 메모리 확장·풀링 범위를 넓힌다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL Root Port**: 호스트 CPU 다이에 집적되어 CXL 트랜잭션을 송수신하는 최상위 포트.
- **CXL Switch / Fabric**: 다중 호스트와 다중 CXL 디바이스를 메쉬/크로스바로 연결하여 동적 메모리 할당 및 공유를 중계하는 패브릭.

</details>

```text
[ 다중 호스트 CXL 패브릭 아키텍처 ]
┌─────────────────────────┐         ┌─────────────────────────┐
│ 호스트 CPU 1 (Root Port)│         │ 호스트 CPU 2 (Root Port)│
└────────────┬────────────┘         └────────────┬────────────┘
             │ [ CXL.io / CXL.cache / CXL.mem ]  │
             └──────────────────┬────────────────┘
                                │
                      [ CXL Switch Fabric ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
 [ Type-1 Device ]       [ Type-2 Device ]       [ Type-3 Device ]
 (메모리 없는 가속기)    (메모리 보유 가속기)    (메모리 확장기)
 (CXL.io + cache)        (CXL.io+cache+mem)      (CXL.io + mem)
```

선의 의미: 호스트 루트 포트, CXL 스위치 패브릭 및 타입별 장치(Type 1/2/3) 간의 인터커넥트 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| CXL.io 프로토콜 | 장치 검색·설정·레지스터 접근·인터럽트 등 PCIe 계열 I/O 의미론 제공 |
| CXL.cache 프로토콜 | 가속기 장치의 호스트 메인 메모리에 대한 하드웨어 수준의 일관적 캐싱 지원 |
| CXL.mem 프로토콜 | 호스트의 장치 연결 메모리에 대한 로드·스토어 접근 지원 |
| CXL 스위치 및 패브릭 | 트래픽 라우팅 및 다중 호스트 메모리 풀링 중계 |

#### 한줄 요약

- 루트 포트와 스위치 패브릭이 장치 유형별 프로토콜을 연결해 가속기·메모리 자원을 확장한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 Memory Read**: CPU가 일반 Load 명령을 실행하면 CXL.mem 프로토콜 패킷으로 변환되어 외부 CXL 메모리에서 데이터를 가져오는 동작.

</details>

```text
[ CPU 메모리 접근 요청 (Load / Store) ]
                 │
                 ▼
     [ 1. 주소 디코딩 및 타겟 판정 ]
                 │
                 ▼
     [ 2. CXL.mem 요청 생성 ]
                 │
                 ▼
     [ 3. 스위치 패브릭 라우팅 ]
                 │
                 ▼
     [ 4. Type-3 장치 메모리 접근 ]
                 │
                 ▼
      데이터 응답 반환·CPU 로드 완료
```

**동작 원리**

1. **주소 디코딩 및 타겟 판정**: 주소 디코딩으로 로컬 또는 CXL 판별
2. **CXL.mem 요청 생성**: 대상 주소와 읽기·쓰기 속성을 CXL.mem 요청으로 변환
3. **스위치 패브릭 라우팅**: CXL 스위치를 통해 대상 디바이스 포트 전달
4. **Type-3 장치 메모리 접근**: 메모리 컨트롤러가 장치 연결 메모리에서 데이터 읽기·쓰기

#### 한줄 요약

- 호스트 주소가 CXL 메모리 영역이면 CXL.mem 요청이 패브릭을 지나 Type-3 장치 메모리에 도달한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Type-1 장치**: 장치 메모리 없이 호스트 메모리를 일관되게 캐싱하는 가속기.
- **Type-2 장치**: 자체 메모리를 보유하고 호스트·장치 메모리를 함께 사용하는 가속기.
- **Type-3 장치**: 장치 연결 메모리를 호스트 주소 공간에 제공하는 메모리 장치.

</details>

| CXL 장치 유형 | 타입 1 (Type-1) | 타입 2 (Type-2) | 타입 3 (Type-3) |
|:---|:---|:---|:---|
| 적용 기준 | 스마트 NIC, DPU 등 자체 메모리가 없거나 캐싱이 필요한 네트워킹 가속 | GPU, FPGA 등 자체 고대역폭 메모리를 보유하며 호스트와 양방향 공유가 필요한 연산 가속 | CXL 메모리 확장기 등 서버의 메모리 용량 확장 및 풀링 전용 장치 |
| 핵심 특징 | CXL.io와 CXL.cache로 호스트 메모리의 일관적 캐싱 지원 | CXL.io·cache·mem을 조합해 장치 메모리와 호스트 메모리 상호 접근 지원 | CXL.io·mem으로 장치 연결 메모리를 호스트 주소 공간에 제공 |
| 한계 | 호스트 메모리 의존성과 일관성 트래픽 관리 필요 | 일관성·주소 관리·장치 메모리 모델의 구현 복잡도 | 로컬 DRAM보다 높은 지연과 링크·패브릭 혼잡 가능성 |

#### 한줄 요약

- 스마트NIC은 **타입 1**, GPU/가속기는 **타입 2**, 메모리 풀링/확장기는 **타입 3**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Memory Tiering (메모리 계층화)**: Hot Data는 고속 로컬 DRAM(Tier 0)에, Cold Data는 CXL 메모리(Tier 1)에 자동 배치하는 OS 커널 메모리 관리 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 확장 메모리의 물리적 접근 지연으로 인한 성능 하락 | **메모리 계층화**와 데이터 온도 기반 배치 적용 | 뜨거운 데이터의 로컬성 유지와 확장 지연 완화 |
| 프로토콜 패킷 간 상호 자원 대기 | 규격·플랫폼이 제공하는 가상 채널·흐름 제어·오류 처리 사용 | 교착 위험과 트래픽 간섭 감소 |
| 다중 호스트·장치에서 스위치 라우팅 경합 | 패브릭 관리와 대역폭 정책, 워크로드 격리 적용 | 꼬리 지연과 자원 경합 완화 |
| 장치 오류·핫리무브 중 메모리 접근 실패 | 오류 격리·페이지 마이그레이션 후 장치 제거 | 장애 영향 범위 축소·서비스 연속성 향상 |

#### 한줄 요약

- CXL 메모리는 지연·경합·장애 범위가 로컬 DRAM과 다르므로 계층화와 패브릭 격리를 함께 설계한다.

## Ⅶ. 결론

- 용량 확장·풀링 이득이 원격 지연보다 크면 **Type-3 CXL 메모리**를 계층화하고, 일관된 공유가 필요한 가속기만 Type-1·2를 적용하며 단순 스트리밍 장치는 PCIe 유지

#### 한줄 요약

- CXL은 모든 장치를 대체하는 링크가 아니라, 메모리 확장과 일관된 공유가 실제로 필요한 경계에 선택하는 표준이다.
