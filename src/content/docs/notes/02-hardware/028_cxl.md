## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CXL(Compute Express Link)**: PCIe 물리 계층 위에서 CPU와 GPU 가속기, 메모리 확장기 간의 하드웨어 캐시 일관성과 직접 메모리 접근을 지원하는 개방형 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트와 디바이스 메모리가 분리되어 매번 DMA 복사 오버헤드가 발생하는 전통적 아키텍처.
- **메모리 풀링(Memory Pooling)**: 데이터센터 내의 다수 서버가 중앙 CXL 스위치에 연결된 메모리 풀을 동적으로 할당/공유하는 기술.

</details>

- 정의/개념: PCIe 물리 계층을 기반으로 CPU, GPU 가속기 및 메모리 확장 장치 간의 고속 I/O, 하드웨어 캐시 일관성, 메모리 직접 접근을 지원하는 개방형 인터커넥트 표준
- 배경/필요성: 가속기-호스트 간 비효율적 데이터 복사 오버헤드를 제거하고, 데이터센터 차원의 **메모리 벽 극복 및 대규모 메모리 풀링(Memory Pooling) 실현**

#### 한줄 요약

- PCIe 기반 위에 **CXL.io, CXL.cache, CXL.mem**을 다중화한 차세대 인터커넥트

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: 장치 열거, 탐색, 레지스터 설정 및 비일관적 DMA I/O를 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기가 호스트 CPU의 메인 메모리를 최저 지연으로 캐싱하고 일관성을 유지하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 PCIe 슬롯에 꽂힌 외부 CXL 메모리를 일반 로컬 DRAM처럼 직접 읽고 쓰는 프로토콜.

</details>

- 단일 물리 링크 위에서 **CXL.io, CXL.cache, CXL.mem** 3종 프로토콜의 동적 다중화 전송
- **CXL.mem**을 통해 CPU 소켓당 메모리 슬롯 한계를 극복하고 테라바이트급 메모리 용량 확장 및 풀링 지원
- 장치 유형에 따른 **하드웨어 캐시 일관성** 보장으로 가속기 프로그래밍 시 명시적 데이터 복사 제거

#### 한줄 요약

- **3종 프로토콜 다중화**와 **하드웨어 캐시 일관성** 기반 테라바이트급 메모리 풀링

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL Root Port**: 호스트 CPU 다이에 집적되어 CXL 트랜잭션을 송수신하는 최상위 포트.
- **CXL Switch / Fabric**: 다중 호스트와 다중 CXL 디바이스를 메쉬/크로스바로 연결하여 동적 메모리 할당 및 공유를 중계하는 패브릭.

</details>

```text
[ 다중 호스트 CXL 패브릭 아키텍처 ]
┌─────────────────────────┐         ┌─────────────────────────┐
│ 호스트 CPU 1 (Root Port)│         │ 호스트 CPU 2 (Root Port)│
└────────────┬────────────┘         └────────────┬────────────┘
             │ [ CXL.io / CXL.cache / CXL.mem ]  │
             └──────────────────┬────────────────┘
                                │
                    [ CXL 3.0 Switch Fabric ]
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
 [ Type-1 Device ]       [ Type-2 Device ]       [ Type-3 Device ]
 (SmartNIC / DPU)        (GPU / AI Accelerator)  (CXL Memory Expander)
 (CXL.io + cache)        (CXL.io+cache+mem)      (CXL.io + mem)
```

선의 의미: 호스트 루트 포트, CXL 스위치 패브릭 및 타입별 장치(Type 1/2/3) 간의 인터커넥트 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| CXL.io 프로토콜 | 가속기 및 메모리 장치 검색, 기본 설정 및 비일관적 입출력 통신 제공 |
| CXL.cache 프로토콜 | 가속기 장치의 호스트 메인 메모리에 대한 하드웨어 수준의 일관적 캐싱 지원 |
| CXL.mem 프로토콜 | 호스트의 확장 장치 메모리에 대한 직접적이고 투명한 읽기 쓰기 엑세스 지원 |
| CXL 스위치 및 패브릭 | 다중 장치 간 복잡한 트래픽 라우팅, 메모리 풀링 및 동적 용량 할당 제공 |

#### 한줄 요약

- **루트 포트·CXL 스위치 패브릭·3종 프로토콜(io/cache/mem)** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 Memory Read**: CPU가 일반 Load 명령을 실행하면 CXL.mem 프로토콜 패킷으로 변환되어 외부 CXL 메모리에서 데이터를 가져오는 동작.

</details>

```text
[ CPU 메모리 접근 요청 (Load / Store) ]
                 │
                 ▼
     [ 1. 물리 주소 디코딩 및 CXL 타겟 판정 ]
                 │
                 ▼
     [ 2. 프로토콜 다중화 (Multiplexer) ]
     ├─ 설정/DMA ─────> CXL.io
     ├─ 가속기 캐시 ──> CXL.cache
     └─ 메모리 접근 ──> CXL.mem
                 │
                 ▼
     [ 3. PCIe PHY 및 CXL Switch 전송 ]
                 │
                 ▼
     [ 4. Type-3 확장 장치 DRAM 컨트롤러 접근 ]
                 │
                 ▼
     [ 5. 데이터 패킷 반환 및 CPU 레지스터 로드 완료 ]
```

**동작 원리**

1. **주소 판정**: CPU가 메모리 주소를 디코딩하여 로컬 DRAM인지 CXL 메모리 영역인지 판별
2. **프로토콜 다중화**: CXL.mem 패킷으로 캡슐화하여 PCIe 물리 계층을 통해 전송
3. **스위치 라우팅**: CXL 스위치를 거쳐 대상 Type-3 메모리 확장기 포트로 패킷 전달
4. **데이터 인출**: Type-3 디바이스 컨트롤러가 로컬 DRAM에서 데이터를 읽어 CXL.mem 데이터 응답 생성
5. **로드 완료**: 응답 데이터가 CPU로 반환되어 100~200ns 내에 일반 메모리 읽기 완료

#### 한줄 요약

- 주소 판정 후 **CXL.mem/cache/io 다중화 전송 $\to$ 확장 메모리 접근 및 로드 완료**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Type-1 vs Type-2 vs Type-3**:
  - Type-1: SmartNIC/DPU (CXL.io + CXL.cache)
  - Type-2: GPU/NPU 가속기 (CXL.io + CXL.cache + CXL.mem)
  - Type-3: 메모리 확장기/풀링 장치 (CXL.io + CXL.mem)

</details>

| 비교 항목 | 타입 1 (Type-1) | 타입 2 (Type-2) | 타입 3 (Type-3) |
|:---|:---|:---|:---|
| 프로토콜 조합 | CXL.io + CXL.cache | CXL.io + CXL.cache + CXL.mem | CXL.io + CXL.mem |
| 대표 장치 및 역할 | 스마트 NIC, DPU (호스트 메모리 캐싱 가속) | GPU, FPGA 가속기 (호스트와 장치 메모리 양방향 공유) | CXL 메모리 확장기 (메모리 용량 확장 및 풀링) |
| 핵심 유스케이스 | 호스트 메모리에 대한 초저지연 캐싱 및 네트워킹 가속 | 호스트-가속기 간 대규모 텐서 메모리 직접 공유 | 서버 DRAM 용량 확장 및 클라우드 동적 메모리 풀링 |
| 한계 및 위험 | 장치 로컬 메모리 미제공, 캐시 스누핑 트래픽 | 고도의 캐시 일관성 제어 복잡도 및 높은 설계 단가 | 호스트 로컬 DRAM 대비 100~200ns 추가 지연(Tiering 필요) |

#### 한줄 요약

- 스마트NIC은 **타입 1**, GPU/가속기는 **타입 2**, 메모리 풀링/확장기는 **타입 3**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Memory Tiering (메모리 계층화)**: Hot Data는 고속 로컬 DRAM(Tier 0)에, Cold Data는 CXL 메모리(Tier 1)에 자동 배치하는 OS 커널 메모리 관리 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 확장 메모리의 물리적 접근 지연이 로컬 메모리보다 느려 발생하는 성능 하락 | 운영체제 수준의 **메모리 계층화** 도입 및 **데이터 온도** 기반 자동 이관 스케줄링 | 뜨거운 데이터의 국소성 유지로 확장 지연 오버헤드 최소화 보장 |
| 프로토콜 패킷 간 상호 자원 대기로 인한 치명적인 프로토콜 시스템 교착 상태 | 물리 계층 상의 **가상 채널** 버퍼 독립 할당 및 완벽한 분리 전송 구현 | 다중화 전송 중 트랜잭션 교착 상태 완벽 방지 및 처리량 보장 |
| 다중 호스트 공유 시 스위치 라우팅 병목으로 인한 심각한 패브릭 대경합 | 패브릭 관리자를 통한 정밀한 트래픽 대역폭 제어 및 품질 서비스 설정 도입 | 갑작스러운 꼬리 지연시간 상승 억제 및 안정적 대역폭 제공 보장 |
| 모듈의 물리적 탈착 및 하드웨어 오류 시 호스트 운영체제 전체 커널의 붕괴 | 고신뢰성 트랩 예외 처리 적용 및 물리적 핫플러그 기반 엄격한 장애 격리 가동 | 신속한 노드 격리 조치를 통한 중단 없는 클라우드 서비스 고가용성 유지 |

#### 한줄 요약

- **메모리 계층화(Tiering)·가상 채널(VC)·패브릭 QoS·핫플러그 격리**로 안정성 확보
