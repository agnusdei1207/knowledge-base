## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **CXL**: Compute Express Link, PCIe 위에서 캐시 일관성과 메모리 공유를 제공하는 규격
- **PCIe**: Peripheral Component Interconnect Express, 고속 직렬 장치 인터커넥트
- **분리 주소 공간**: 호스트와 장치가 각자 주소 공간을 가져 복사와 소프트웨어 동기화가 필요한 구조

</details>

- 정의/개념: PCIe 물리 계층 위에서 호스트와 장치의 **캐시 일관성과 메모리 공유** 를 제공하는 인터커넥트 규격
- 배경/필요성: 분리 주소 공간의 **복사•동기화 부담** 완화

#### 한줄 요약

- CXL은 호스트와 장치가 일관된 캐시•메모리 접근을 사용해 복사와 메모리 중복을 줄인다

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **I/O**: Input/Output, 호스트와 장치 사이의 입출력
- **CXL.io**: 장치 설정과 비일관 I/O를 지원하는 프로토콜
- **CXL.cache**: 장치의 호스트 메모리 일관 캐시를 지원하는 프로토콜
- **CXL.mem**: 호스트가 장치 메모리를 일반 로드•스토어로 접근하게 하는 프로토콜
- **프로토콜 다중화**: 하나의 PCIe 물리 링크에 I/O•캐시•메모리 요청을 구분해 함께 전달하는 방식

</details>

- 한 링크가 **CXL.io•CXL.cache** 요청을 다중화
- **CXL.mem** 기반 장치 메모리 로드•스토어와 계층화
- **하드웨어 일관성** 기반의 복사 없는 메모리 공유

#### 한줄 요약

- CXL은 한 링크에 I/O•캐시•메모리 프로토콜을 싣고, 확장 메모리는 로컬 DRAM보다 느린 별도 계층으로 관리한다

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **루트 포트**: 프로세서에서 CXL 장치 경로가 시작되는 호스트 측 연결점
- **CXL 스위치**: 요청을 대상 CXL 장치로 분기하는 구성요소
- **CXL 패브릭**: 여러 호스트와 장치를 연결하는 경로망
- **메모리 풀링**: 여러 호스트가 공용 장치 메모리에서 필요한 용량을 동적으로 할당받는 방식

</details>

```text
[CXL 호스트]
      |
CXL 패브릭 경계
      |
[CXL 루트 포트] -- [CXL 스위치] -- [CXL 장치 집합]
```

선의 의미: 호스트가 루트 포트로 패브릭에 접속하고 스위치가 장치 집합을 공유 연결하는 정적 경계•네트워크 관계다.

| 구성요소 | 책임 |
|:---|:---|
| CXL 호스트 | 프로세서 요청과 **메모리 일관성** 관리 |
| CXL 루트 포트 | 호스트•장치 **경로 시작** |
| CXL 스위치 | 요청 분기와 **메모리 풀링** |
| CXL 장치 집합 | 가속기 캐시•**확장 메모리** 제공 |

#### 한줄 요약

- 루트 포트와 스위치가 호스트 요청을 일관성을 유지한 채 CXL 장치로 전달한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **타입 3 장치**: CXL.io와 CXL.mem으로 확장 메모리를 제공하는 장치
- **직결 경로**: 루트 포트에서 장치로 직접 요청을 전달하는 경로
- **스위치 경로**: 패브릭 스위치를 거쳐 요청을 전달하는 경로
- **로드 완료**: 장치 메모리에서 읽은 데이터가 CXL.mem 응답으로 호스트 CPU에 반환된 상태
- **중앙 처리 장치(Central Processing Unit, CPU)**: 장치 메모리에 로드 요청을 보내고 반환 데이터를 사용하는 호스트 프로세서
- **동적 임의 접근 메모리(Dynamic Random-Access Memory, DRAM)**: 타입 3 장치가 확장 용량으로 제공하는 휘발성 메모리

</details>

```text
                    [호스트•장치 요청]
                             |
                 1. 요청 목적•프로토콜 판정
                    /          |          \
             [장치 설정] [장치의 호스트 캐시] [장치 메모리]
                 |             |              |
              [CXL.io]     [CXL.cache]     [CXL.mem]
                 \             |              /
                  2. PCIe PHY 링크 다중화
                             |
                   3. 직결•스위치 경로 선택
                             |
                  4. 대상 장치•메모리 처리
                             |
                 [일관성 응답•로드 완료]
```

**동작 원리**

- **1. 요청 목적•프로토콜 판정**: I/O•캐시•메모리 요구 구분
- **2. PCIe PHY 링크 다중화**: 세 프로토콜을 한 링크에 전송
- **3. 직결•스위치 경로 선택**: 주소 매핑으로 대상 장치 라우팅
- **4. 대상 장치•메모리 처리**: 일관성 또는 로드•스토어 수행

#### 한줄 요약

- 직결은 지연을 줄이고, 스위치 경유는 지연을 더하는 대신 여러 호스트•장치의 메모리 풀링을 지원한다

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: PCIe 물리 계층에 캐시 일관성과 메모리 프로토콜을 추가한 인터커넥트
- **MMIO**: Memory-Mapped Input/Output, 메모리 주소로 장치 레지스터에 접근하는 방식
- **DMA**: Direct Memory Access, 장치가 CPU 개입 없이 메모리와 직접 전송하는 방식
- **하드웨어 일관성**: 장치와 호스트의 캐시 사본을 프로토콜이 자동으로 최신 상태로 맞추는 성질
- **로드•스토어 접근**: 별도 전송 API 대신 일반 메모리 명령으로 장치 메모리를 읽고 쓰는 방식

</details>

| 인터커넥트 규격 | CXL | PCIe |
|:---|:---|:---|
| 적용 기준 | 일관성이 필요한 **캐시•메모리 접근** | 장치 I/O와 DMA 전송이면 충분할 때 |
| 핵심 특징 | **하드웨어 일관성** 기반 로드•스토어 접근 | **MMIO•DMA** 기반 비일관 전송 |
| 한계 | 링크 경유 **접근 지연** 과 상호운용 검증 | 공유 데이터의 **소프트웨어 동기화** |

> 요약: CXL은 PCIe에 일관성 추가

#### 한줄 요약

- PCIe는 장치 전송에, CXL은 일관된 캐시•메모리 접근과 용량 확장에 적합하다

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **데이터 온도**: 최근 접근 빈도와 지연 민감도로 데이터를 로컬•확장 계층에 배치하는 기준
- **패브릭 경합**: 여러 호스트와 장치의 요청이 공유 링크와 스위치 큐에 몰리는 상태
- **RAS**: Reliability, Availability, Serviceability, 오류 탐지•격리•복구 능력
- **상호운용성**: 서로 다른 업체의 CXL 장치가 함께 동작하는 능력

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 로컬 DRAM보다 긴 **CXL 메모리 접근 지연** | **데이터 온도•접근 빈도** 에 따른 계층 배치 | 지연 민감 데이터의 **로컬 DRAM 유지** |
| 여러 호스트•장치의 **패브릭 대역폭 경합** | 경로별 **대역폭•큐 깊이** 감시와 풀 할당 제한 | **혼잡•꼬리 지연** 완화 |
| 일관성 요청 정체로 **장치 진행 중단** | **타임아웃•재시도** 와 순환 의존성 검증 | **교착** 방지 |
| **링크•스위치 장애** 와 구현 차이 | 장애 도메인 격리, **RAS•상호운용성** 검증 | **서비스 지속성** 확보 |

> 사례: **CXL.cache** 기반 호스트 메모리 공유

#### 한줄 요약

- CXL.cache로 복사를 줄이되 접근 지연•패브릭 경합•장애 범위를 함께 검증한다

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **CXL 메모리**: 로컬 DRAM보다 느리지만 공유•용량 확장을 제공하는 계층
- **메모리 계층화**: 지연과 용량이 다른 로컬 DRAM과 CXL 메모리를 별도 단계로 배치하는 방식
- **링크 지연**: CXL 프로토콜과 전송 경로를 거치며 로컬 DRAM보다 추가되는 접근 시간

</details>

- 공유•용량 이득이 링크 지연보다 크면 **CXL** 계층 적용

#### 한줄 요약

- 용량 확장과 공유 이득이 링크 지연보다 클 때 CXL을 별도 메모리 계층으로 적용한다
