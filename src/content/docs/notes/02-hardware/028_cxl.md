## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: PCIe 물리 계층을 기반으로 호스트 프로세서와 가속기, 메모리 확장 장치 간에 I/O, 캐시 일관성, 메모리 공유 의미론을 단일 인터페이스로 다중화하여 제공하는 고속 개방형 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트 CPU와 주변 장치가 서로 독립된 메모리 주소 공간을 사용하여 데이터 교환 시 명시적인 DMA 복사 오버헤드가 발생하는 전통적 구조.
- **메모리 풀링(Memory Pooling)**: 분산된 CXL 메모리 자원을 단일 공유 풀로 구성하여 여러 호스트의 워크로드 요구량에 따라 동적으로 할당하고 회수하는 자원 가상화 기법.

</details>

- 정의/개념: PCIe 물리 계층 위에서 I/O·캐시 일관성·메모리 접근이라는 서로 다른 의미론을 한 링크에 다중화한 **CXL** 표준
- 배경/필요성: **분리 주소 공간**은 접근할 때마다 명시적 복사를 강요하고, 서버마다 고정된 메모리는 남아도 다른 서버가 쓸 수 없음

#### 한줄 요약
- CXL이 PCIe를 대체하지 않고 그 위에 얹힌 것이 채택의 결정적 조건이었으며, 새 배선을 요구했다면 표준 경쟁에서 살아남지 못했을 설계다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: PCIe 표준 기반의 장치 열거, 탐색, 구성 레지스터 설정 및 비일관적 대용량 DMA 데이터 전송을 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기가 호스트 프로세서의 시스템 메모리를 저지연으로 직접 캐싱하고 하드웨어적으로 일관성을 유지할 수 있도록 지원하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 CXL 장치에 장착된 메모리를 표준 로드/스토어 명령어로 직접 접근할 수 있도록 주소 공간을 확장하는 프로토콜.

</details>

- 단일 링크에서 **CXL.io**와 용도별 **CXL.cache**·**CXL.mem** 의미론을 다중화해 전송
- **CXL.mem**으로 장치 메모리를 호스트 주소 공간에 편입해 **메모리 풀링** 기반 마련
- 하드웨어 일관성을 **CXL.cache**가 담당해 명시적 복사와 동기화 코드를 제거

#### 한줄 요약
- 세 프로토콜을 분리해 둔 덕분에 장치가 필요한 것만 구현할 수 있고, 이 선택적 구현이 곧 다음 절의 장치 유형 구분을 만든다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL 루트 포트(CXL Root Port)**: 호스트 CPU 다이 내부에 직접 통합되어 CXL.io, CXL.cache, CXL.mem 트랜잭션을 인코딩·디코딩하여 외부 장치로 중계하는 최상위 인터페이스 포트.
- **CXL 스위치/패브릭(CXL Switch/Fabric)**: 다수의 호스트 CPU와 다양한 CXL 엔드포인트 장치 간의 트래픽을 크로스바 또는 메시 토폴로지로 라우팅하여 대규모 메모리 풀링 및 동적 공유를 중계하는 패브릭 스위치.

</details>

```text
[CXL 시스템]
├─ 호스트 CPU
│  └─ CXL Root Port (CXL.io / CXL.cache / CXL.mem 다중화)
├─ CXL Switch·Fabric
└─ CXL 장치
   ├─ Type-1 (메모리 없는 가속기 · io + cache)
   ├─ Type-2 (메모리 보유 가속기 · io + cache + mem)
   └─ Type-3 (메모리 확장기 · io + mem)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 장치 유형별 괄호 안이 그 장치가 실제로 구현하는 프로토콜 조합

| 구성요소 | 책임 |
|:---|:---|
| **CXL 루트 포트** | 호스트 측에서 세 프로토콜 트랜잭션을 송수신 |
| **CXL.io** | 장치 검색·설정·레지스터 접근 등 PCIe 계열 I/O 제공 |
| **CXL.cache** | 가속기가 호스트 메모리를 하드웨어 일관성 아래 캐싱 |
| **CXL.mem** | 호스트가 장치 연결 메모리를 로드·스토어로 접근 |
| **CXL 스위치/패브릭** | 트래픽 라우팅과 다중 호스트 메모리 풀링 중계 |

#### 한줄 요약
- 스위치가 들어오는 순간 메모리는 서버에 붙은 부품이 아니라 네트워크 자원이 되며, 이 전환이 CXL이 노리는 실제 변화다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 메모리 읽기(Type-3 Memory Read)**: CPU가 일반 로드 명령어를 발행하면 메모리 컨트롤러가 이를 CXL.mem 패킷으로 변환하여 외부 CXL 메모리 모듈에서 데이터를 인출해 오는 동작.

</details>

```text
CPU 메모리 접근 요청 (Load / Store)
        │
   주소 디코딩: 어느 영역인가?
   ┌────┴────────┐
로컬 DRAM 영역   CXL 메모리 영역
   │                │
메모리 컨트롤러    CXL.mem 요청 생성
직접 접근            │
   │           스위치 패브릭 라우팅
   │                │
   │           Type-3 장치 메모리 접근
   └────┬───────────┘
        │
   데이터 반환·로드 완료
```

분기 결과: 두 경로가 같은 로드 명령에서 갈리므로 프로그램은 구분할 수 없지만, 패브릭을 거치는 쪽은 홉 수만큼 지연이 더해져 로컬 DRAM과 성능 특성이 달라짐

#### 한줄 요약
- **Type-3 메모리 읽기**가 일반 로드와 구분되지 않는다는 투명성이 장점이자 함정이며, 코드를 고치지 않아도 되는 대신 느려진 원인도 코드에 드러나지 않는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **타입 1 장치(Type-1 Device)**: 자체 메모리가 없으며 CXL.io와 CXL.cache를 사용하여 호스트 메모리를 하드웨어 일관성 있게 직접 캐싱하는 가속기 장치.
- **타입 2 장치(Type-2 Device)**: 자체 고속 메모리를 탑재하고 CXL.io, CXL.cache, CXL.mem을 모두 활용하여 호스트와 장치 간 양방향 메모리 공유 및 일관성을 유지하는 복합 가속기.
- **타입 3 장치(Type-3 Device)**: CXL.io와 CXL.mem을 기반으로 장치에 연결된 DRAM/비휘발성 메모리를 호스트의 물리 주소 공간으로 확장해 주는 메모리 확장 전용 장치.

</details>

| CXL 장치 유형 | 타입 1 (Type-1) | 타입 2 (Type-2) | 타입 3 (Type-3) |
|:---|:---|:---|:---|
| 적용 기준 | 스마트 NIC, DPU 등 캐싱이 필요한 네트워킹 가속 | GPU, FPGA 등 호스트와 양방향 공유가 필요한 연산 가속 | 서버의 메모리 용량 확장 및 풀링 전용 장치 |
| 핵심 특징 | **CXL.io**와 **CXL.cache** 기반 호스트 메모리 일관 캐싱 | **CXL.io·cache·mem** 조합으로 양방향 메모리 공유 | **CXL.io·mem**으로 장치 메모리를 호스트 주소 공간 확장 |
| 한계 | 호스트 메모리 의존성 및 일관성 트래픽 오버헤드 | 양방향 일관성 제어로 인한 하드웨어 구현 복잡도 | 로컬 DRAM 대비 접근 지연 증가 및 패브릭 경합 |

#### 한줄 요약
- 세 유형은 성능 등급이 아니라 메모리를 누가 소유하느냐로 갈리며, **타입 2 장치**만이 양방향 소유를 다루기 때문에 구현 복잡도가 비대칭적으로 높다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 계층화(Memory Tiering)**: 접근 빈도가 높은 핫 데이터는 초고속 로컬 DRAM(Tier 0)에, 콜드 데이터는 CXL 확장 메모리(Tier 1)에 동적으로 분할 배치하는 OS 커널 메모리 관리 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 확장 메모리의 물리적 접근 지연으로 인한 성능 하락 | **메모리 계층화**와 데이터 온도 기반 배치 적용 | 뜨거운 데이터의 로컬성 유지와 확장 지연 완화 |
| 프로토콜 패킷 간 상호 자원 대기 | 규격·플랫폼이 제공하는 가상 채널·흐름 제어·오류 처리 사용 | 교착 위험과 트래픽 간섭 감소 |
| 다중 호스트·장치에서 스위치 라우팅 경합 | 패브릭 관리와 대역폭 정책, 워크로드 격리 적용 | 꼬리 지연과 자원 경합 완화 |
| 장치 오류·핫리무브 중 메모리 접근 실패 | 오류 격리·페이지 마이그레이션 후 장치 제거 | 장애 영향 범위 축소·서비스 연속성 향상 |

#### 한줄 요약
- 네 문제 모두 메모리가 서버 밖으로 나가면서 생기므로, CXL 도입은 용량 증설이 아니라 장애 도메인을 하나 더 만드는 결정으로 다뤄야 한다.

## Ⅶ. 결론

- 용량 확장·풀링 이득이 원격 지연보다 크면 **타입 3 장치**를 **메모리 계층화**와 함께 도입하고, 일관된 공유가 필요한 가속기만 타입 1·타입 2를 적용하며 단순 스트리밍 장치는 PCIe 유지

#### 한줄 요약
- CXL의 값어치는 링크 속도가 아니라 메모리를 서버 경계에서 떼어 낼 수 있다는 데 있으므로, 그 분리가 필요 없는 시스템에서는 지연만 늘어난다.
