## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 고속 PCIe 물리 계층을 기반으로 호스트 프로세서, 가속기, 메모리 확장 장치 간에 I/O, 캐시 일관성, 메모리 공유 의미론을 단일 링크로 다중화하여 제공하는 차세대 개방형 인터커넥트 표준.
- **분리 주소 공간(Disjoint Address Space)**: 호스트 CPU와 주변 장치가 독립된 주소 공간을 사용하여 데이터 교환 시 명시적인 DMA 복사 오버헤드가 발생하는 기존 시스템 구조.
- **메모리 풀링(Memory Pooling)**: 분산된 CXL 메모리 자원을 단일 공유 풀로 구성하여 여러 서버가 필요에 따라 동적으로 메모리를 할당받고 반납하는 자원 가상화 기술.

</details>

- 정의/개념: PCIe 물리 계층 위에서 I/O(CXL.io), 캐시 일관성(CXL.cache), 메모리 확장(CXL.mem)의 3대 프로토콜을 다중화하여 장치 간 이종 연결을 지원하는 **CXL(Compute Express Link) 개방형 인터커넥트 표준**
- 배경/필요성: 기존 PCIe I/O 방식의 **분리 주소 공간 복사 오버헤드, 캐시 비일관성 및 서버 간 메모리 파편화(Stranded Memory) 한계 극복**

#### 한줄 요약
- CXL은 PCIe 물리 링크 위에서 I/O, 캐시 일관성, 메모리 확장을 단일 인터페이스로 융합하여 차세대 메모리 풀링과 가속기 협업을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: PCIe 표준 기반의 장치 검색, 구성 레지스터 설정 및 비일관적 대용량 DMA 데이터 전송을 담당하는 필수 기본 프로토콜.
- **CXL.cache**: 가속기(GPU/FPGA)가 호스트 CPU의 시스템 메모리를 초저지연으로 직접 캐싱하고 하드웨어적으로 일관성을 유지할 수 있도록 지원하는 프로토콜.
- **CXL.mem**: 호스트 CPU가 CXL 확장 장치에 장착된 메모리를 표준 로드/스토어(Load/Store) 명령어로 직접 접근할 수 있도록 주소 공간을 확장하는 프로토콜.

</details>

- 3대 프로토콜 단일 링크 다중화: **CXL.io(I/O), CXL.cache(캐시 일관성), CXL.mem(메모리 확장)**을 동적으로 다중화(FLIT 기반)하여 지연시간 극소화
- 메모리 풀링 및 확장: **CXL.mem**을 통해 서버 슬롯에 장착된 DRAM을 호스트 물리 주소 공간으로 확장하고, 스위치를 매개로 다중 호스트 간 **메모리 풀링** 실현
- 하드웨어 캐시 일관성: **CXL.cache**를 통해 가속기와 호스트 간 데이터 교환 시 소프트웨어 복사 및 동기화 오버헤드 원천 제거

#### 한줄 요약
- CXL은 io, cache, mem 3대 프로토콜을 통해 하드웨어 캐시 일관성과 동적 메모리 확장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CXL 루트 포트(CXL Root Port)**: 호스트 CPU 다이 내부에 직접 통합되어 CXL.io, CXL.cache, CXL.mem 패킷을 인코딩/디코딩하는 최상위 인터페이스.
- **CXL 스위치/패브릭(CXL Switch/Fabric)**: 다수의 호스트 CPU와 다양한 CXL 엔드포인트 장치 간의 트래픽을 크로스바 토폴로지로 라우팅하여 대규모 메모리 풀링을 중계하는 스위치.

</details>

```text
[CXL 시스템 아키텍처]
 ├─ [호스트 CPU 서버]
 │   ├─ CPU 연산 코어 ── L1/L2/L3 캐시 ── 로컬 DRAM 채널
 │   └─ [CXL 루트 포트 (CXL Root Port)] ──► CXL.io / CXL.cache / CXL.mem 다중화
 │
 ├─ [CXL 스위치 / 패브릭 (CXL Switch Fabric)] ──► 다중 호스트 메모리 풀링 중계
 │
 └─ [CXL 엔드포인트 장치 분류]
     ├─ Type-1: 가속기 (스마트 NIC / DPU) ──► CXL.io + CXL.cache
     ├─ Type-2: 가속기 (GPU / FPGA / NPU) ──► CXL.io + CXL.cache + CXL.mem
     └─ Type-3: 메모리 확장기 (CXL DRAM/SSD) ─► CXL.io + CXL.mem
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 장치 유형별 프로토콜 지원 조합 관계; 스위치가 다중 호스트와 엔드포인트를 중계함

| 장치 유형 | 프로토콜 조합 | 핵심 엔지니어링 책임 | 주요 적용처 |
|:---|:---|:---|:---|
| **Type-1 장치** | **CXL.io + CXL.cache** | 자체 메모리 없이 호스트 시스템 메모리를 직접 캐싱 | 스마트 NIC, DPU, 보안 가속기 |
| **Type-2 장치** | **CXL.io + CXL.cache + CXL.mem** | 자체 고속 메모리를 보유하고 호스트와 양방향 메모리 공유/일관성 유지 | 차세대 AI 가속기, GPU, FPGA |
| **Type-3 장치** | **CXL.io + CXL.mem** | 장치에 장착된 DRAM을 호스트의 물리 주소 공간으로 확장 | **CXL 메모리 확장기, 메모리 풀링 장치** |

#### 한줄 요약
- CXL 시스템은 루트 포트, 스위치 패브릭, 그리고 Type-1(캐싱 가속), Type-2(복합 가속), Type-3(메모리 확장) 장치로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Type-3 메모리 읽기**: CPU가 CXL 영역 주소로 로드 명령을 발행하면 IMC가 CXL.mem 읽기 요청 패킷을 생성하여 외부 CXL 메모리에서 데이터를 인출해 오는 동작.

</details>

```text
1. CPU 코어의 Load / Store 메모리 접근 명령어 실행
                      │
                      ▼
2. 통합 메모리 제어기(IMC)의 주소 디코딩
   ┌──────────────────┴──────────────────┐
[ 로컬 DRAM 주소 영역 ]               [ CXL 확장 메모리 주소 영역 ]
   │                                     │
   ▼                                     ▼
로컬 DDR 채널 직접 접근 (50~80ns)     3. CXL.mem 프로토콜 읽기 요청 패킷 생성
   │                                     │
   │                                     ▼
   │                              4. CXL 루트 포트 ➔ PCIe PHY 전송 (스위치 라우팅)
   │                                     │
   │                                     ▼
   │                              5. Type-3 CXL 메모리 컨트롤러 도달 ➔ DRAM 데이터 인출
   │                                     │
   │                                     ▼
   │                              6. CXL.mem 응답 패킷 전송 (지연시간 $\approx 150\sim 200\text{ns}$)
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. CPU 코어로 데이터 반환 완료 (프로그래머 관점에서 일반 메모리와 동일 투명성)
```

분기 결과: **로컬 DRAM은** 최단 지연(수십 ns)으로 완료되고, **CXL 메모리는** 링크 전송 지연이 더해지나 소프트웨어 수정 없이 투명하게 확장됨

#### 한줄 요약
- CPU가 주소를 발행하면 IMC가 판별하여 로컬 메모리는 직접 읽고, CXL 메모리는 CXL.mem 패킷으로 인출하여 반환한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | CXL (Compute Express Link) | PCIe (PCI Express) | 독점 인터커넥트 (NVLink / Infinity Fabric) |
|:---|:---|:---|:---|
| 핵심 프로토콜 | **CXL.io + CXL.cache + CXL.mem** | PCIe I/O (비일관적 DMA) | 독자 캐시 일관성 및 메모리 공유 |
| 캐시 일관성 | **하드웨어 캐시 일관성 완벽 지원** | 미지원 (소프트웨어 드라이버 동기화) | 지원 (동일 벤더 장비 간에만 지원) |
| 메모리 확장 방식 | **로드/스토어 직접 주소 지정 (CXL.mem)** | I/O 버퍼 매핑 및 DMA 전송 | 독자 공유 메모리 매핑 |
| 표준화 및 생태계 | **개방형 산업 표준 (Intel, AMD, ARM 등)** | 개방형 표준 (PCI-SIG) | 폐쇄형 독점 규격 (특정 벤더 종속) |
| 주요 적용 분야 | **서버 메모리 확장, 메모리 풀링, 이종 가속** | 전통적 주변장치 (SSD, NIC, GPU) | 동일 벤더 GPU 클러스터 간 초고속 통신 |

#### 한줄 요약
- PCIe는 비일관 I/O에 그치고 독점 링크는 폐쇄적인 반면, CXL은 개방형 표준으로 캐시 일관성과 메모리 확장을 모두 실현한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 계층화(Memory Tiering)**: 접근 빈도가 높은 핫 데이터는 로컬 DRAM(Tier 0)에, 콜드 데이터는 CXL 확장 메모리(Tier 1)에 배치하는 OS 계층화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CXL 메모리의 PCIe 링크 경유로 인한 접근 지연시간 증가(150~200ns) | **OS 레벨 메모리 계층화(Tiering) 및 NUMA 노드 가중치 설정** | 핫 데이터 로컬성 유지 및 평균 지연시간 단축 |
| 다중 호스트가 단일 CXL 풀에 동시 접근 시 패브릭 대역폭 경합 | **CXL 스위치 대역폭 QoS 및 다중 포트 링크 어그리게이션** | 대역폭 병목 해소 및 공정한 자원 분배 보장 |
| 원격 CXL 메모리 장치 장애 시 서버 전체 커널 패닉 위험 | **메모리 장애 격리(Poisoning) 및 비동기 페이지 마이그레이션** | 시스템 무중단 고가용성(HA) 확보 |

#### 한줄 요약
- 실무에서는 메모리 계층화로 지연을 완화하고, QoS로 대역폭 경합을 통제하며, 장애 격리로 시스템 신뢰성을 확보한다.

## Ⅶ. 결론

- 데이터센터의 메모리 벽과 자원 파편화를 극복하기 위해 **PCIe 5.0/6.0 기반의 CXL 2.0/3.0 인터커넥트 표준을 서버 인프라에 도입**하고, 서버 메모리 용량 확장을 위해 **Type-3 CXL 메모리 풀링 아키텍처를 구축**하며, 소프트웨어 계층에서는 **OS 메모리 계층화(Tiering) 및 NUMA 최적화 기술**을 융합하는 고효율 차세대 데이터센터 메모리 아키텍처 확립

#### 한줄 요약
- CXL은 개방형 표준 기반으로 하드웨어 캐시 일관성과 메모리 풀링을 완성하는 차세대 데이터센터 인터커넥트의 핵심이다.
