## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리(Processing Near Memory)**: 메모리 모듈 컨트롤러 인근이나 3D 로직 다이에 연산 유닛을 배치하여 공정 변경을 피하면서 연산 유연성을 확보하는 하드웨어 가속 기술이다.
- **왕복 전송량(Round-Trip Transfer Volume)**: 프로세서와 메모리 버스 사이를 오가는 대용량 데이터 읽기 및 쓰기 총 패킷 수량이다.

</details>

- 정의: 메모리 모듈 컨트롤러 인근에 연산 유닛을 배치하여 데이터 버스 **왕복 전송량**을 억제하는 **메모리 근접 처리** 기술
- 배경: 기존 메모리 공정 변경의 어려움을 극복하고 표준 반도체를 유지하면서 연산의 유연성을 하드웨어적으로 확보하기 위함

#### 한줄 요약

- 모듈 주변 버퍼나 로직 다이에 프로그래밍이 가능한 연산기를 배치하여 데이터 이동 병목을 줄이면서도 범용적인 연산을 지원하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 논리 공정으로 제조되어 복잡한 산술 논리 연산, 필터링, 압축 등의 제어 로직을 높은 집적도로 구동하는 칩이다.
- **메모리 근접 처리 모듈(PNM DIMM)**: 버퍼 인근에 연산 로직을 탑재한 스마트 메모리 모듈이다.
- **메모리 인접 로직(Near-Memory Logic)**: 메모리 채널 대역폭을 거쳐 나오는 데이터 흐름을 최단 위치에서 직접 스캔하고 압축하는 하드웨어 블록이다.

</details>

- **로직 다이**에 표준 논리 공정을 적용할 수 있어 프로그래밍 가능한 다양한 연산 복잡도를 지원함.
- 표준 칩 변경 없이 **메모리 근접 처리 모듈** 형태로 기존 시스템과 원활하게 상용 결합이 가능함.
- **메모리 인접 로직**을 통해 프로세서로 원본을 전송하기 전에 자체적인 필터링과 결과 축약을 수행함.

#### 한줄 요약

- 표준 칩 생태계를 유지하면서 주변 로직 다이를 활용해 유연한 병렬 연산을 지원하고 외부 버스 트래픽을 선제적으로 감축한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(Host Interface)**: 프로세서와 모듈 간의 오프로드 명령 및 캐시 일관성 통신을 중계하는 초고속 상호 연결 버스이다.
- **메모리 근접 처리 런타임(PNM Runtime)**: 운영체제 커널상에서 실행되어 전용 명령 발송, 버퍼 락업 및 장애 예외를 관리하는 소프트웨어 계층이다.

</details>

```text
[ 메모리 근접 처리 (PNM) 아키텍처 ]
+-------------------------------------------------------------+
| 호스트 프로세서 (제어기 및 드라이버)                        |
+-------------------------------------------------------------+
                              │
         [ 상호 연결 고속 버스 (PCIe / CXL 등) ]
                              │
+-------------------------------------------------------------+
| 메모리 근접 처리 모듈 (스마트 기판)                         |
|  +-------------------------------------------------------+  |
|  | 모듈 컨트롤러 및 메모리 인접 연산 로직 (ASIC/FPGA)    |  |
|  |  └─ 스캔 / 필터 / 압축 / 집계 유닛                    |  |
|  +-------------------------------------------------------+  |
|  +-------------------------------------------------------+  |
|  | 표준 메모리 칩 배열 (다중 채널 접근)                  |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **호스트 인터페이스** | 프로세서와 모듈 간의 오프로드 명령 및 데이터 일관성 통신 중계 |
| **메모리 인접 로직** | 프로세서 전송 전 대상 데이터의 스캔, 필터링, 압축 및 집계 수행 |
| 표준 메모리 칩 배열 | 연산에 필요한 대용량 원본 데이터 저장 및 다중 채널 접근 경로 제공 |
| **메모리 근접 처리 런타임** | 소유권 장벽 제어, 연산 이관 명령 발송 스케줄링 및 장애 격리 관리 |

#### 한줄 요약

- 호스트 연결 인터페이스 아래에 연산 전용 인접 로직을 두고 그 뒤에 표준 칩 배열을 배치하는 3단 계층 구조를 띤다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 하드웨어 가동 시 프로세서와 근접 로직이 동일한 데이터 영역에 동시 접근하지 못하도록 제어권을 명시적으로 분리하는 장벽이다.
- **장애 격리(Fault Isolation)**: 모듈 내 하드웨어 오류나 타임아웃 발생 시 서버 전체의 커널 붕괴로 번지지 않도록 예외를 트랩하는 보호 기술이다.

</details>

```text
[ 호스트 데이터베이스 쿼리 스캔 요청 발생 ]
                      │
                      ▼
            [ 1. 이관 판정 및 발송 ]
                      │
                      ▼
            [ 2. 소유권 장벽 설정 ]
                      │
                      ▼
            [ 3. 근접 연산 하드웨어 실행 ]
                      │ (다중 채널 데이터 인출 및 스캔)
                      ▼
            [ 4. 데이터 결과 축약 ]
                      │
                      ▼
            [ 5. 결과 반환 및 장벽 해제 ]
```

### 동작 원리

1. 이관 판정 및 발송: 연산 이득을 런타임에 확인하고 근접 처리 명령을 모듈로 발송함.
2. 소유권 장벽 설정: 공유 버퍼에 대한 프로세서의 동시 쓰기 시도를 차단하는 **소유권 장벽**을 설정함.
3. 근접 연산 실행: 배열 칩에서 데이터를 다중 채널로 읽어와 즉시 스캔 및 필터링함.
4. 결과 축약: 유효한 데이터 행과 집계 연산된 최종 압축 결과만 출력 버퍼에 기록함.
5. 결과 반환 및 장벽 해제: 연산 완료 응답을 반환하고 장벽을 해제하여 정상 접근을 재개함.

#### 한줄 요약

- 이관 여부를 판단한 후 소유권을 명확히 분리하고 칩 밖으로 나오기 직전에 연산을 완결한 뒤 결과만 돌려준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **최단 이동(Shortest Movement)**: 데이터 이동 거리를 칩 내부 뱅크 바로 옆 수준으로 극단적으로 줄이는 메모리 설계의 물리적 지향점이다.
- **연산 표현력(Operation Expressiveness)**: 아키텍처 상에서 수용 가능한 기계어 명령어의 종류와 분기 제어, 부동소수점 정밀도 등 다채로운 연산을 수용하는 유연성이다.

</details>

| 비교 항목 | 메모리 근접 처리 (PNM) | 메모리 내 연산 (PIM) |
|:---|:---|:---|
| 연산기 탑재 위치 | 메모리 모듈 제어기 주변 및 3D 하단 다이에 배치 | 칩 내부의 각 메모리 뱅크 및 미세 셀 바로 옆에 배치 |
| 메모리 공정 변형 | 표준 칩과 별도의 로직을 결합하여 공정 유지 용이 | 구현에 따라 다이 및 베이스 로직 설계의 극단적 변형 필수 |
| **연산 표현력** | 논리 공정 기반으로 복잡한 연산도 수용하는 높은 표현력 | 내부 면적과 열 발산 제약으로 매우 정형화된 연산에 국한 |
| 데이터 이동 거리 | 메모리 칩에서 모듈 버퍼로 전송해야 하는 중간 이동 발생 | 셀에서 뱅크 연산기로 전송하는 극단적인 **최단 이동** 달성 |
| 시스템 물리 이식성 | 버스 호환 인터페이스를 통해 시스템 장착 이식성 우수 | 전용 메모리 인터페이스 제약과 핀 배치 한계로 이식 복잡 |

#### 한줄 요약

- 메모리 근접 처리는 연산의 유연성과 기존 인프라 호환성에 방점을 찍었고, 메모리 내 연산은 극단적인 데이터 이동 감축에 방점을 찍었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **완료 장벽(Completion Barrier)**: 연산 완료 응답 패킷을 수신하기 전까지 프로세서의 종속 연산 진행을 일시적으로 대기시키는 동기화 펜스이다.
- **채널 편향(Channel Skew)**: 특정 채널로만 데이터 읽기 요청이 편중되어 인접 연산기의 다중 채널 병렬 처리 능력이 저하되는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근접 처리 지연이 단순 메모리 읽기 지연을 초과하는 성능 오버헤드 | 데이터 축약률을 런타임에 동적 비교하여 선별적 연산 오프로드 수행 | 무의미한 소용량 연산의 이관 차단 및 실질 가속 효과 100% 보장 |
| 호스트와 모듈 내 연산기가 동일 버퍼에 동시 접근 시 치명적 데이터 오염 | **소유권 장벽** 및 **완료 장벽**을 통한 하드웨어 동기화 통제 연동 | 메모리 대경합 물리적 차단 및 연산 실행 전후 데이터 일관성 보장 |
| 모듈 내부 하드웨어 로직 오류 시 시스템 커널 전체의 붕괴 파동 발생 | 엄격한 접근 타임아웃, 예외 재시도 제어 및 물리적 **장애 격리** 가동 | 국소 로직 오류 수습 및 호스트 서버 커널의 회복 탄력성 즉각 확보 |
| 특정 메모리 채널에 주소가 편중되어 연산 병렬성을 훼손하는 **채널 편향** | 컨트롤러 수준의 고도화된 주소 인터리빙 구조 및 큐 깊이 모니터링 | 다중 채널 병렬 처리율 상향 및 실효 데이터 연산 대역폭 극대화 |

#### 한줄 요약

- 런타임에 이득을 비교하고 소유권을 통제하며 채널 부하를 분산함으로써 유연한 연산 장치의 실효성을 극대화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **근접 처리 아키텍처 선택 기준(PNM Architecture Selection Criteria)**: 대상 알고리즘 연산의 변경 빈도, 표준 칩의 재사용성, 데이터 축약률을 정밀 평가하여 구현을 선택하는 결정 기준이다.

</details>

- 연산 변경이 잦고 모듈 시스템 호환이 중요하면 **근접 처리**, 이동 최소화가 최우선이면 **내부 연산**을 선택함

#### 한줄 요약

- 연산 로직의 복잡도와 인프라 교체 비용을 분석하여 가장 현실적인 메모리 데이터 이동 병목 해소 방안을 채택해야 한다.
