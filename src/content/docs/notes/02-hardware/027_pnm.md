## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리(Processing Near Memory, PNM)**: DRAM 셀 내부가 아닌 메모리 컨트롤러, 로직 다이 또는 DIMM/CXL 모듈 기판에 연산 유닛을 배치하여 표준 상용 DRAM을 그대로 활용하면서 호스트-메모리 간 전송량을 획기적으로 줄이는 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 호스트 프로세서와 메모리 모듈 간의 시스템 버스를 통과하는 요청 및 대규모 원본 데이터의 전체 패킷 트래픽.

</details>

- 정의/개념: 표준 DRAM 모듈, CXL 컨트롤러 또는 베이스 다이에 연산 가속 로직을 배치하여 대규모 원본 데이터의 호스트 전송을 최소화하는 **메모리 근접 컴퓨팅 아키텍처**
- 배경/필요성: DRAM 셀 어레이 내부 연산기 집적에 따른 공정 결함 및 수율 저하 회피와 상용 DRAM 기반 데이터 이동 병목 및 전송 전력 절감

#### 한줄 요약
- PNM은 표준 DRAM 모듈/CXL 컨트롤러에 연산기를 배치하여 제조 난이도를 낮추고 데이터 이동을 줄이는 실용적 근접 컴퓨팅 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 표준 첨단 파운드리 CMOS 공정으로 제조되어 복합 제어, 데이터 필터링, 압축, 해시 연산 등을 고속 처리할 수 있는 전용 가속 칩.
- **CXL 기반 PNM 모듈**: CXL.mem 및 CXL.io 프로토콜을 통해 표준 서버 슬롯에 장착되어 캐시 일관성 및 메모리 확장을 지원하면서 근접 연산을 수행하는 하드웨어 장치.

</details>

- 특수 DRAM 수정 없이 **상용 표준 DRAM**과 인터페이스 규격을 그대로 활용하여 제조 수율과 양산성 확보
- 메모리 컨트롤러 내 고성능 **로직 다이 탑재**를 통해 데이터 스캔, 필터링, 압축 등의 복합 전처리 연산 가속
- **CXL 프로토콜(CXL.mem/io)** 기반의 표준 서버 슬롯 연결을 통해 시스템 유연성 및 캐시 일관성 보장

#### 한줄 요약
- 표준 DRAM을 변경 없이 그대로 쓰면서 컨트롤러의 로직 다이에서 복합 연산을 처리하므로 상용화와 호환성이 뛰어나다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(Host Interface)**: PCIe/CXL 물리 계층을 통해 호스트 CPU와 PNM 모듈 간의 제어 명령 및 요약 결과를 고속 통신하는 인터페이스.
- **PNM 런타임(PNM Runtime)**: OS 및 사용자 계층에서 실행되어 워크로드 오프로딩 여부를 동적으로 판별하고 메모리 동기화 장벽을 제어하는 소프트웨어 계층.

</details>

```text
[근접 메모리 연산 (PNM) 아키텍처]
  │
  ├─ [호스트 서버] (CPU 코어·PNM 런타임)
  │
  ├─ [CXL 통신 패브릭] (CXL.io·CXL.mem 링크)
  │
  └─ [CXL 기반 PNM 모듈]
        ├─ [CXL 컨트롤러] (프로토콜 엔진)
        ├─ [PNM 로직 다이] (스캔·필터링·집계)
        └─ [표준 DRAM 어레이] (상용 DDR5 메모리)
```

선의 의미: 호스트 서버, CXL 패브릭 및 PNM 모듈 내부(로직 다이·DRAM)의 계층 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU·런타임 | 워크로드의 연산 축약률 분석 기반 **오프로딩 스케줄링** 및 동기화 제어 |
| CXL 인터페이스 | **CXL.io 및 CXL.mem** 프로토콜을 통해 저지연 명령 전달 및 캐시 일관성 유지 |
| PNM 로직 다이 | 표준 DRAM에서 인출한 대용량 데이터에 대해 **스캔·필터링·압축** 연산 수행 |
| 표준 DRAM 어레이 | 특수 공정 수정 없는 상용 DRAM 칩으로 구성되어 **대용량 저장소** 제공 |

#### 한줄 요약
- PNM 로직 다이가 CXL 인터페이스 뒤이자 표준 DRAM 어레이 앞이라는 중간 계층에 끼어들어 스캔·필터링을 대신 수행하므로, 원본 전량을 호스트까지 실어 나르던 링크 전송이 요약 결과 전송으로 줄어든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 근접 연산 수행 중 호스트와 PNM 컨트롤러가 동일 버퍼에 동시 접근하여 발생하는 데이터 충돌을 방지하는 동기화 장벽.

</details>

```text
[호스트 데이터 질의/분석 요청]
       │
       ▼
 1. 오프로딩 손익 판정
   ├─ [낮은 축약률] ──> 호스트 CPU 직접 인출 및 연산
   └─ [높은 축약률: PNM 오프로드]
       │
       ├─ 2. CXL 경유 소유권 장벽 설정 (캐시 무효화)
       ├─ 3. 모듈 로컬 DRAM 원본 데이터 인출
       ├─ 4. 로직 다이 하드웨어 스캔·필터링
       └─ 5. 요약 결과만 CXL 버스 전송
```

분기 결과: **데이터 축약률**이 높은 질의는 PNM 로직 다이에서 처리하여 CXL 버스 트래픽을 90% 이상 절감하나, 축약률이 낮은 작업은 호스트가 직접 인출하여 오프로딩 오버헤드를 방지함

**동작 원리**

1. **오프로딩 손익 판정**: 호스트 PNM 런타임이 데이터 크기와 예상 필터링 축약률을 계산하여 모듈 오프로드 실행 여부 결정
2. **CXL 소유권 장벽 설정**: 모듈로 연산을 위임하기 전 해당 메모리 버퍼의 호스트 캐시 라인을 무효화하고 CXL 일관성 소유권을 로직 다이로 이전
3. **로컬 DRAM 대용량 인출**: PNM 로직 다이가 온보드 전용 메모리 채널을 통해 표준 DRAM 어레이로부터 원본 데이터를 병렬 인출
4. **로직 다이 고속 스캔·필터링**: 내장된 전용 ASIC 코어가 조건 검색, 데이터 스캔, 레코드 필터링 및 압축 연산을 실시간 수행
5. **요약 결과 반환**: 압축·선별된 최종 결과 패킷만 CXL.mem 버스를 통해 호스트 CPU로 반환하고 버퍼 소유권 복귀

#### 한줄 요약
- 런타임이 축약률을 평가하여 유리할 때만 모듈 로직 다이로 연산을 오프로딩하고 필터링된 결과만 호스트에 반환한다.

## Ⅴ. 종류 및 비교

| 근접 처리 아키텍처 | PNM (Near Memory) | PIM (In Memory) | 호스트 중심 처리 (Host-Centric) |
|:---|:---|:---|:---|
| 적용 기준 | 상용 호환성과 복합 필터링·데이터베이스 질의 가속 시 | 단순 대규모 행렬 곱셈 및 딥러닝 텐서 병렬 연산 시 | 복잡한 분기 제어 및 범용 OS 애플리케이션 실행 시 |
| 핵심 특징 | **컨트롤러 로직 다이**와 표준 DRAM 결합 | **DRAM 뱅크 내부** 연산 코어 직접 집적 | **CPU/GPU 연산 코어**에서 데이터 인출 후 처리 |
| 한계 | CXL 링크 왕복 지연 및 모듈 인터페이스 대역폭 한계 | 특수 DRAM 공정에 따른 수율 저하 및 집적도 희생 | 시스템 버스 대역폭 고갈 및 **데이터 전송 전력 급증** |

#### 한줄 요약
- 복합 데이터 필터링과 호환성에는 PNM이 적합하고, 단순 대규모 행렬 연산에는 PIM이, 범용 제어에는 호스트 중심 처리가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장애 격리(Fault Isolation)**: PNM 모듈 내부 연산기 오류나 타임아웃 발생 시 호스트 커널 패닉을 방지하고 소프트웨어 폴백으로 전환하는 신뢰성 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 축약률 미달 시 오프로딩 통신 지연에 따른 성능 역전 | 런타임 비용 모델 기반 **동적 오프로딩 판정** | 손익분기점 초과 작업만 선별 위임하여 지연 단축 |
| 호스트 CPU와 PNM 로직 간 동일 버퍼 동시 접근 충돌 | **CXL 소유권 장벽** 및 캐시 플러시 제어 | 데이터 정합성 보장 및 레이스 컨디션 차단 |
| 모듈 내부 하드웨어 연산 타임아웃 및 하드웨어 결함 | 타임아웃 감시 및 **소프트웨어 폴백** 엔진 가동 | 하드웨어 장애 시에도 호스트 CPU 기반 중단 없는 실행 |

#### 한줄 요약
- 실무에서는 동적 비용 모델로 오프로드를 선별하고, CXL 일관성으로 충돌을 방어하며, 소프트웨어 폴백으로 장애를 격리한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크 메모리 풀링(Compute Express Link Memory Pooling, CXL Memory Pooling)**: 복수의 호스트 서버가 고속 CXL 패브릭을 통해 공유 메모리 풀에 동적으로 접근하여 유휴 메모리를 제거하고 용량을 탄력적으로 확장하는 기술.
- **도메인 특화 가속기(Domain-Specific Accelerator, DSA)**: 추천 시스템의 임베딩 연산, 벡터 검색 등 특정 워크로드에 하드웨어적으로 최적화되어 데이터 필터링을 전담 가속하는 유닛.

</details>

- 상용 DRAM 공정과 모듈 생태계를 보존하는 PNM은 CXL 패브릭과 결합하여, 풀드 메모리 스위치 단에서 대규모 벡터 검색 및 필터링을 직접 수행하는 **컴퓨트 익스프레스 링크 메모리 풀링(CXL Memory Pooling)** 및 **도메인 특화 가속기(DSA)** 통합 구조로 진화 추세
- 시스템 소프트웨어 및 분산 인프라 설계 시에는 데이터 축약률과 CXL 인터페이스 지연을 대조하는 비용 모델을 정교화하고, 가속기 결함 시 호스트 CPU로 안전하게 전환되는 장애 격리 및 폴백(Fallback) 메커니즘을 사전 완비하는 공학적 통찰 필요

#### 한줄 요약
- PNM은 CXL 메모리 풀링 환경에서 도메인 특화 가속기로 진화하고 있으며, 실무에서는 연산 축약률 기반의 동적 오프로딩 판정과 견고한 장애 폴백 체계 확보가 핵심이다.
