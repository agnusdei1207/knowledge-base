## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리 (Processing Near Memory, PNM)**: 메모리 다이 자체보다는 메모리 모듈 컨트롤러 인근(CXL Controller, DIMM Buffer) 또는 3D 로직 다이 상에 연산 유닛을 배치하여, 표준 DRAM 공정 변경 최소화와 연산 로직 유연성을 동시 확보하는 근접 처리 기술.
- **왕복 전송량(Round-Trip Transfer Volume)**: 호스트 CPU와 메모리 버스 사이를 오가는 대용량 데이터 읽기/쓰기 총 패킷 수량.

</details>

- 정의/개념: 메모리 미세 셀 내부가 아닌 메모리 모듈/버퍼 칩 인근(Near Memory)에 프로그래밍 가능한 로직 연산기를 배치하여 버스 **왕복 전송량(Round-Trip Transfer Volume)**을 억제하는 **메모리 근접 처리(Processing Near Memory, PNM)**.
- 배경/필요성: PIM(Processing-In-Memory) 방식의 메모리 셀 미세 공정 변경 어려움과 정형 연산자 제약을 극복하고, 표준 DRAM 칩을 유지하면서 CXL/DIMM 로직 레벨에서 가변 연산(Filter, Scan, Aggregation)을 구동하기 위해 등장.

#### 한줄 요약
- 메모리 모듈(DIMM/CXL) 인근 버퍼 또는 로직 다이에 프로그래밍 가능한 연산기를 배치하여 유연한 연산 오프로드 및 데이터 이동 절감을 달성하는 기술.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이 (Logic Die)**: 표준 CMOS 논리 공정으로 제조되어 복잡한 ALU, 필터링, 압축 로직을 높인 정밀 구동 칩.
- **PNM DIMM(Processing Near Memory DIMM)**: DDR 메모리 모듈의 버퍼 인근에 PNM 연산 로직을 둔 스마트 메모리 모듈.
- **메모리 인접 로직 (Near-Memory Logic)**: 메모리 채널 대역폭을 타고 올라오는 64-bit 데이터 흐름을 인접 위치에서 직접 스캔, 필터, 압축하는 하드웨어 블록.

</details>

- **로직 다이(Logic Die)** 상에서 표준 CMOS 논리 공정을 사용할 수 있어 다양한 **프로그래밍 가능 연산(Programmable Operation)** 복잡도 지원.
- 표준 DRAM 칩 변경 없이 **PNM DIMM** 또는 CXL 모듈 형태로 기존 서브시스템에 상용 결합 가능.
- **메모리 인접 로직**으로 호스트 전송 전 데이터를 필터링하고 **결과 축약** 수행.

#### 한줄 요약
- 표준 DRAM 변경 없이 CXL/DIMM 인근 CMOS 로직 다이를 활용하여 연산 유연성을 보장하고 데이터 이동 병목을 해소함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스 (Host Interface / CXL.mem / CXL.cache)**: 호스트 CPU와 PNM 모듈 간의 오프로드 명령 및 일관성 통신을 중계하는 CXL/PCIe 호스트 버스.
- **PNM 런타임 (PNM Runtime Environment)**: 호스트 OS 커널상에서 실행되어 PNM 전용 커맨드 발송, 메모리 버퍼 락업 및 완료 예외를 관리하는 라이브러리.

</details>

```text
[ Processing Near Memory (PNM) Architecture ]
┌───────────────────────────────────────────────────────────┐
│ Host CPU (Host Memory Controller & CXL.mem Host Driver)   │
├───────────────────────────────────────────────────────────┤
│ PCIe / CXL High-Speed Interconnect Bus                    │
├───────────────────────────────────────────────────────────┤
│ PNM Module (Smart CXL / PNM-DIMM Board)                   │
│  ├─ CXL Controller & PNM Near-Memory Logic (FPGA / ASIC)  │
│  │   └─ Scan / Filter / Compression / Aggregation Unit    │
│  └─ Standard DRAM Chips Array (Multi-Channel Access)      │
└───────────────────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| 호스트 인터페이스 | **명령•데이터•완료 응답** 전달 |
| 메모리 인접 로직 | **Scan•Filter•압축•집계** 수행 |
| 표준 DRAM 배열 | 다중 채널 **원본 데이터 저장** 제공 |
| PNM 런타임 | **소유권•이관•장애 격리** 관리 |

#### 한줄 요약
- CXL/PCIe Host Interface, Near-Memory Logic(FPGA/ASIC), Standard DRAM Chips 및 PNM Runtime이 유기적으로 연동함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽 (Ownership Barrier)**: PNM 연산 가동 시 호스트 CPU와 PNM 로직이 동일 버퍼에 동시 접근하지 못하도록 제어권을 명시적으로 넘겨주는 순서화 로직.
- **장애 격리 (Fault Isolation)**: PNM 로직의 하드웨어 오류나 타임아웃 발생 시 호스트 시스템 전체 커널 붕괴로 전파되지 않도록 로직을 분리 트랩하는 기술.

</details>

```text
[ Host CPU Database Scan Request (e.g., SQL WHERE Clause) ]
                         │
                         ▼
        [ 1. 이관 판정•발송 ]
                         │
                         ▼
        [ 2. 소유권 장벽 설정 ]
                         │
                         ▼
        [ 3. 근접 연산 실행 ]
                         │ (Read Standard DRAM Multi-Channels)
                         ▼
        [ 4. 결과 축약 ]
                         │
                         ▼
        [ 5. 결과 반환•장벽 해제 ]
```

### 동작 원리

1. **이관 판정•발송**: 축약 이득을 확인하고 PNM 명령을 전달함.
2. **소유권 장벽 설정**: 공유 버퍼의 호스트 동시 쓰기를 차단함.
3. **근접 연산 실행**: DRAM 데이터를 스캔•필터링함.
4. **결과 축약**: 유효 행과 집계 결과만 출력 버퍼에 기록함.
5. **결과 반환•장벽 해제**: 완료 응답 후 호스트 접근을 재개함.

#### 한줄 요약
- Offload Dispatch -> Ownership Barrier Lock -> Near-Memory Logic Filtering -> Result Reduction -> Host Return 및 Barrier Unlock 순으로 실행됨.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **최단 이동 (Shortest Movement)**: 데이터 이동 거리를 칩 내부 뱅크 수준으로 줄이는 PIM의 물리적 최극단 지향점.
- **연산 표현력 (Operation Expressiveness)**: 아키텍처 상에서 수용 가능한 기계어 명령어, 복잡 분기문, 부동소수점 정밀도의 다채로운 연산 지원 유연성.

</details>

| 비교 항목 | PNM 구조 (Processing Near Memory) | PIM 구조 (Processing in Memory) |
|:---|:---|:---|
| **연산기 탑재 위치** | 메모리 모듈 컨트롤러, CXL 버퍼, 3D 하단 다이 | DRAM 칩 내부 뱅크/셀 바로 옆 |
| **DRAM 공정 변형** | 표준 DRAM과 별도 로직 결합 가능 | 구현에 따라 DRAM 다이•베이스 로직 변경 |
| **연산 표현력** | FPGA•ASIC 기반 비교적 유연한 연산 | 내부 면적•열 제약으로 정형 연산 중심 |
| **데이터 이동 거리** | 메모리 칩 -> 모듈 버퍼 전송 (중간 이동) | 셀 -> 뱅크 연산기 전송 (**최단 이동**) |
| **시스템 이식성** | **우수함** (CXL, CXL.mem 기반 호환 장착) | 메모리 인터페이스 제약으로 이식 복잡 |
| **주요 채택 제품** | CXL PNM, SmartSSD, PNM-DDR/CXL | HBM-PIM, Aquabolt-XL PIM |

#### 한줄 요약
- PNM은 표준 DRAM 공정을 유지하고 높은 연산 표현력과 CXL 이식성에 강점을 가지며, PIM은 뱅크 수준 최단 데이터 이동 및 극단적 전력 절감에 강점을 가짐.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **완료 장벽 (Completion Barrier)**: PNM 연산 완료 응답 패킷을 받기 전까지 호스트 CPU의 종속 연산 진행을 일시 제어하는 동기화 펜스.
- **채널 편향 (Channel Skew)**: 특정 DRAM 채널로만 접근이 쏠려 PNM 인접 연산기의 다채널 병렬 처리가 저하되는 현상.

</details>

| 문제 및 병목 원인 | 실무적 대책 및 해결 방안 | 기대 효과 |
|:---|:---|:---|
| PNM 오프로드 지연이 데이터를 그냥 읽는 지연보다 커지는 오버헤드 | 데이터 축약률과 **이관 지연**을 런타임 비교하여 가변 오프로드 | 무의미한 소용량 오프로드 차단 및 가속 효과 보장 |
| 호스트 CPU와 PNM 연산기가 동일 버퍼에 동시 접근 시 데이터 오염 | **소유권 장벽** 및 **완료 장벽(Completion Barrier)** 동기화 연동 | 메모리 대경합 차단 및 실행 전후 데이터 일관성 보장 |
| PNM 로직 오류 발생 시 호스트 서버 전체 락업 및 커널 Panic | **타임아웃(Timeout)**, **재시도** 및 **장애 격리(Fault Isolation)** | 로직 오류 수습 및 호스트 커널 회복 탄력성 확보 |
| 특정 메모리 채널에 주소가 편중되는 **채널 편향(Channel Skew)** | CXL 컨트롤러 주소 인터리빙 및 **채널별 큐 깊이** 모니터링 | 다채널 병렬 처리율 상향 및 실효 대역폭 극대화 |

#### 한줄 요약
- Offload Latency 런타임 비교, Ownership/Completion Barrier 적용, Fault Isolation 차단 및 CXL Channel Interleaving을 구동함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PNM 아키텍처 선택 기준 (PNM Architecture Selection Criteria)**: 알고리즘 연산 변경 빈도, 표준 DRAM 활용성, CXL 하드웨어 호환성 및 데이터 축약률을 정밀 평가하여 PNM 구현을 선택하는 결정 프레임워크.

</details>

- 연산 변경이 잦고 모듈 호환이 중요하면 **PNM**, 이동 최소화면 **PIM** 선택.

#### 한줄 요약
- 축약률•표현력•일관성 비용을 기준으로 PNM 이관 범위를 결정함.
