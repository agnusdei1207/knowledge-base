## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PNM(Processing Near Memory)**: 메모리 칩 내부를 수정하지 않고, 메모리 모듈 컨트롤러(CXL/DIMM)나 베이스 로직 다이에 연산 유닛을 배치하는 가속 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 프로세서와 메모리 버스 사이를 오가는 원본 데이터 읽기/쓰기 패킷의 총량.

</details>

- 정의/개념: 메모리 칩 내부 공정 변경 없이 모듈 컨트롤러(CXL/DIMM) 또는 베이스 로직 다이에 연산 유닛(ASIC/FPGA)을 배치하여 데이터 이동 병목을 해소하는 가속 아키텍처
- 배경/필요성: 메모리 공정 변경 없이 표준 DRAM 칩을 활용하면서 **데이터베이스 스캔/필터링 등 복잡한 연산 유연성과 시스템 호환성 확보**

#### 한줄 요약

- 표준 메모리 주변 로직 다이/컨트롤러에 연산기를 배치하여 **유연한 데이터 오프로드 구현**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 첨단 파운드리 논리 공정으로 제조되어 복합 산술 연산, 데이터 필터링, 압축을 고속 처리하는 가속 칩.
- **PNM CXL/DIMM**: 표준 PCIe/CXL 슬롯에 장착되어 메모리 확장과 데이터 필터링 가속을 동시에 수행하는 스마트 모듈.

</details>

- **로직 다이(ASIC/FPGA)**에 표준 논리 공정을 적용하여 복합 분기 및 부동소수점 등 다양한 연산 유연성 지원
- 표준 DRAM 칩을 그대로 활용하여 기존 서버 마더보드 및 **CXL 인터페이스**와의 높은 시스템 호환성 보장
- **메모리 인접 로직**을 통해 호스트 CPU로 원본을 전송하기 전 자체 스캔, 필터링 및 집계 축약 수행

#### 한줄 요약

- 표준 DRAM 칩을 그대로 활용하며 **로직 공정 기반의 고도화된 연산 표현력** 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(CXL.mem / CXL.io)**: PCIe 물리 계층 위에서 캐시 일관성과 직접 메모리 접근 및 오프로드 명령을 전송하는 버스.
- **PNM 런타임**: 호스트 OS 상에서 실행되어 연산 오프로드 판정, 메모리 동기화 장벽 및 예외 처리를 관장하는 소프트웨어 계층.

</details>

```text
[ 메모리 근접 처리 (PNM) 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 프로세서 (Host CPU / DB Query Engine)                │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ CXL / PCIe 고속 상호 연결 버스 ]
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ PNM 모듈 (CXL Type-2/Type-3 스마트 기판)                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 모듈 컨트롤러 및 인접 연산 로직 (ASIC / FPGA)         │  │
│  │  └─ DB Scan / Filter / Sort / Compression Engine      │  │
│  └───────────────────────────┬───────────────────────────┘  │
│                              │ [ 다중 채널 로컬 메모리 버스 ] │
│  ┌───────────────────────────┴───────────────────────────┐  │
│  │ 표준 상용 DRAM 칩 배열 (DDR5 / LPDDR5 Components)     │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트 인터페이스(PCIe/CXL), 모듈 컨트롤러 연산 로직(ASIC/FPGA) 및 표준 DRAM 칩 배열 간의 PNM 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 인터페이스 | 프로세서와 모듈 간의 오프로드 명령 및 데이터 일관성 통신 중계 |
| 메모리 인접 로직 | 프로세서 전송 전 대상 데이터의 스캔, 필터링, 압축 및 집계 수행 |
| 표준 메모리 칩 배열 | 연산에 필요한 대용량 원본 데이터 저장 및 다중 채널 접근 경로 제공 |
| 메모리 근접 처리 런타임 | 소유권 장벽 제어, 연산 이관 명령 발송 스케줄링 및 장애 격리 관리 |

#### 한줄 요약

- **호스트 I/F(CXL)·PNM 모듈 컨트롤러(연산 로직)·표준 DRAM 배열** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 연산 가동 중 호스트 CPU와 PNM 로직이 동일 버퍼에 동시 쓰기를 하지 못하도록 차단하는 동기화 펜스.

</details>

```text
[ 호스트 데이터베이스 테이블 스캔 쿼리 발생 ]
                      │
                      ▼
            [ 1. 오프로드 판정 및 명령 발송 ]
                      │
                      ▼
            [ 2. 메모리 영역 소유권 장벽 설정 ]
                      │
                      ▼
            [ 3. PNM 컨트롤러 데이터 인출 및 연산 ]
                      │ (로컬 채널에서 대용량 데이터 필터링)
                      ▼
            [ 4. 유효 조건 데이터 추출 및 결과 축약 ]
                      │
                      ▼
            [ 5. 축약 결과만 호스트 반환 및 장벽 해제 ]
```

**동작 원리**

1. **오프로드 판정**: 호스트 런타임이 데이터 크기와 필터 조건을 분석하여 PNM 오프로드 결정
2. **소유권 분리**: 대상 메모리 영역에 대해 CPU 캐시 플러시 및 소유권 장벽 설정
3. **근접 연산**: 모듈 컨트롤러가 로컬 DRAM에서 수십 GB의 데이터를 고속 인출하여 조건 대조 및 필터링 수행
4. **결과 축약**: 필터링을 통과한 수 MB의 레코드만 선별하여 호스트 반환 버퍼에 적재
5. **완료 통보**: 연산 완료 인터럽트를 호스트로 전송하고 메모리 소유권 장벽 해제

#### 한줄 요약

- 오프로드 판정 후 **소유권 장벽 설정 $\to$ 근접 스캔/필터링 $\to$ 결과 축약 반환**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PNM vs PIM vs Host-Centric**:
  - PNM: 컨트롤러 위치, 첨단 로직 공정, 높은 연산 표현력, 표준 DRAM 활용
  - PIM: 메모리 뱅크 위치, 메모리 공정 제약, 단순 연산(MAC), 최고 대역폭
  - Host-Centric: 프로세서 코어, 완전 범용 연산, 데이터 이동 병목 발생

</details>

| 비교 항목 | 메모리 근접 처리 (PNM) | 메모리 내 연산 (PIM) | 호스트 중심 연산 (Host-Centric) |
|:---|:---|:---|:---|
| 적용 기준 | 데이터베이스 필터링, 압축 등 메모리 모듈 수준의 연산 오프로드 | 인공지능 행렬 곱셈 등 데이터 이동 최소화가 필수적인 대규모 벡터 연산 | 복잡한 제어 로직 및 범용 스칼라 연산 처리 |
| 핵심 특징 | 메모리 컨트롤러나 로직 다이에 연산기를 탑재하여 표준 DRAM과의 호환성 유지 | 메모리 뱅크 내부에 단순 연산기를 집적하여 칩 내부의 초광폭 대역폭 직접 활용 | 호스트 프로세서의 코어 연산기를 활용하여 데이터 페치 후 중앙 집중형 처리 |
| 한계 | 메모리 칩과 모듈 컨트롤러 간의 물리적 버스 이동에 따른 잔여 오버헤드 존재 | 메모리 공정 특성상 복잡한 논리 회로 탑재가 곤란하며 높은 제조 단가 수반 | 호스트와 메모리 간 외부 버스 병목으로 인한 심각한 전력 낭비와 지연 발생 |

#### 한줄 요약

- PNM은 **표준 칩 호환성과 연산 유연성**, PIM은 **극단적 이동 감축**, Host는 **범용 제어**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Fault Isolation(장애 격리)**: PNM 모듈 내부 연산기에서 예외나 타임아웃 발생 시 호스트 커널 패닉을 방지하고 소프트웨어 폴백으로 전환하는 신뢰성 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근접 처리 지연이 단순 메모리 읽기 지연을 초과하는 성능 오버헤드 | 데이터 축약률을 런타임에 동적 비교하여 선별적 연산 오프로드 수행 | 무의미한 소용량 연산의 이관 차단 및 실질 가속 효과 100% 보장 |
| 호스트와 모듈 내 연산기가 동일 버퍼에 동시 접근 시 치명적 데이터 오염 | **소유권 장벽** 및 **완료 장벽**을 통한 하드웨어 동기화 통제 연동 | 메모리 대경합 물리적 차단 및 연산 실행 전후 데이터 일관성 보장 |
| 모듈 내부 하드웨어 로직 오류 시 시스템 커널 전체의 붕괴 파동 발생 | 엄격한 접근 타임아웃, 예외 재시도 제어 및 물리적 **장애 격리** 가동 | 국소 로직 오류 수습 및 호스트 서버 커널의 회복 탄력성 즉각 확보 |
| 특정 메모리 채널에 주소가 편중되어 연산 병렬성을 훼손하는 **채널 편향** | 컨트롤러 수준의 고도화된 주소 인터리빙 구조 및 큐 깊이 모니터링 | 다중 채널 병렬 처리율 상향 및 실효 데이터 연산 대역폭 극대화 |

#### 한줄 요약

- **축약률 동적 비교·소유권 장벽(Barrier)·장애 격리·주소 인터리빙**으로 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL-PNM 상용화**: CXL Type-2/3 스마트 메모리 확장기에 DPU/FPGA를 탑재하여 데이터센터 DB 가속 및 벡터 검색을 선도.

</details>

- 복잡한 쿼리/그래프 연산 및 빠른 상용화 환경에서 **CXL-PNM 및 스마트 DIMM 기반 실용적 가속 채택**

#### 한줄 요약

- **연산 복잡도와 인프라 호환성**을 고려한 실용적 근접 가속 솔루션 구축
