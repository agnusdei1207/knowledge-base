## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리(Processing Near Memory, PNM)**: DRAM 셀 내부가 아닌 메모리 컨트롤러, 로직 다이 또는 DIMM/CXL 모듈 기판에 연산 유닛을 배치하여 표준 상용 DRAM을 그대로 활용하면서 호스트-메모리 간 전송량을 획기적으로 줄이는 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 호스트 프로세서와 메모리 모듈 간의 시스템 버스를 통과하는 요청 및 대규모 원본 데이터의 전체 패킷 트래픽.

</details>

- 정의/개념: 메모리 컨트롤러 인접 연산기로 **왕복 전송량**을 줄이는 **PNM**
- 배경/필요성: PIM 공정 복잡도와 호스트 버스의 **데이터 이동 지연** 증가

#### 한줄 요약
- PNM은 표준 DRAM 모듈/CXL 컨트롤러에 연산기를 배치하여 제조 난이도를 낮추고 데이터 이동을 줄이는 실용적 근접 컴퓨팅 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 표준 첨단 파운드리 CMOS 공정으로 제조되어 복합 제어, 데이터 필터링, 압축, 해시 연산 등을 고속 처리할 수 있는 전용 가속 칩.
- **CXL 기반 PNM 모듈**: CXL.mem 및 CXL.io 프로토콜을 통해 표준 서버 슬롯에 장착되어 캐시 일관성 및 메모리 확장을 지원하면서 근접 연산을 수행하는 하드웨어 장치.

</details>

- 특수 공정 없이 **표준 DRAM**을 사용해 제조 복잡도 완화
- 컨트롤러의 **로직 다이**로 필터링·압축 가속
- **CXL 인터페이스** 기반 표준 서버 슬롯 확장

#### 한줄 요약
- 표준 DRAM을 변경 없이 그대로 쓰면서 컨트롤러의 로직 다이에서 복합 연산을 처리하므로 상용화와 호환성이 뛰어나다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(Host Interface)**: PCIe/CXL 물리 계층을 통해 호스트 CPU와 PNM 모듈 간의 제어 명령 및 요약 결과를 고속 통신하는 인터페이스.
- **PNM 런타임(PNM Runtime)**: OS 및 사용자 계층에서 실행되어 워크로드 오프로딩 여부를 동적으로 판별하고 메모리 동기화 장벽을 제어하는 소프트웨어 계층.

</details>

```text
[CXL 기반 PNM 서브시스템]
├── [호스트 CPU 및 런타임] (오프로드 스케줄링 및 런타임 제어)
├── [CXL 인터페이스] (CXL.io 및 CXL.mem 프로토콜 엔진)
├── [PNM 로직 다이] (스캔, 필터링, 압축 가속 연산 코어)
└── [표준 DRAM 어레이] (대용량 데이터 저장 표준 메모리 채널)
```

선/분기 의미: 트리 구조(`├──`, `└──`)는 CXL-PNM 모듈의 하드웨어 및 소프트웨어 계층 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU·런타임 | **오프로딩 스케줄링**과 동기화 제어 |
| CXL 인터페이스 | **CXL.mem** 기반 명령·결과 전송 |
| PNM 로직 다이 | 스캔·필터링 등 **복합 연산** 수행 |
| 표준 DRAM 어레이 | 데이터 저장과 **로컬 대역폭** 제공 |

#### 한줄 요약
- PNM 시스템은 호스트 런타임, CXL 인터페이스, PNM 로직 다이, 표준 상용 DRAM 칩의 4단계 계층으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 근접 연산 수행 중 호스트와 PNM 컨트롤러가 동일 버퍼에 동시 접근하여 발생하는 데이터 충돌을 방지하는 동기화 장벽.

</details>

```text
[호스트 애플리케이션의 대규모 데이터 처리 요청]
                          │
                          ▼
1. 오프로딩 손익 판정
       ┌──────────────────┴──────────────────┐
 [ 축약률 낮음 (오프로드 비효율) ]     [ 축약률 높음 (오프로드 유리) ]
       │                                     │
       ▼                                     ▼
[호스트 CPU가 메모리 직접 인출]        2. 소유권 이전·동기화
       │                                     │
       │                                     ▼
       │                              3. DRAM 데이터 인출
       │                                     │
       │                                     ▼
       │                              4. 스캔·필터링·압축
       │                                     │
       │                                     ▼
       │                              5. 요약 결과 CXL 전송
       └──────────────────┬──────────────────┘
                          │
                          ▼
[호스트 프로세서의 최종 결과 수신 및 소유권 복귀]
```

분기 결과: **데이터 축약률**이 높을 때만 모듈 내부 연산을 수행하여 트래픽을 절감하고, 단순 읽기는 호스트가 직접 처리함

**동작 원리**

1. **오프로딩 손익 판정**: 축약률로 호스트·PNM 실행 선택
2. **소유권 이전·동기화**: 대상 버퍼의 접근 주체 전환
3. **DRAM 데이터 인출**: 로직 다이가 로컬 데이터를 조회
4. **스캔·필터링·압축**: 모듈 내부에서 데이터 축약
5. **요약 결과 CXL 전송**: 축약 결과만 호스트로 반환

#### 한줄 요약
- 런타임이 축약률을 평가하여 유리할 때만 모듈 로직 다이로 연산을 오프로딩하고 필터링된 결과만 호스트에 반환한다.

## Ⅴ. 종류 및 비교

| 근접 처리 구조 | PNM | PIM | 호스트 중심 처리 |
|:---|:---|:---|:---|
| 적용 기준 | 복합 필터링·호환성 우선 | 단순 대규모 병렬 연산 | 범용 제어·복잡한 분기 |
| 핵심 특징 | **로직 다이·표준 DRAM** 결합 | **뱅크 내부 연산기** 집적 | **CPU·GPU** 중심 처리 |
| 한계 | CXL 왕복과 오프로딩 비용 | 공정 복잡도와 연산 제약 | 시스템 버스 데이터 이동 병목 |

#### 한줄 요약
- 복합 데이터 필터링과 호환성에는 PNM이 적합하고, 단순 대규모 행렬 연산에는 PIM이, 범용 제어에는 호스트 중심 처리가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장애 격리(Fault Isolation)**: PNM 모듈 내부 연산기 오류나 타임아웃 발생 시 호스트 커널 패닉을 방지하고 소프트웨어 폴백으로 전환하는 신뢰성 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 오프로드 지연 역전 | 비용 모델 기반 **동적 오프로딩** 판정 엔진 적용 | 손익분기점 이상 작업만 선별 처리 |
| 메모리 동시 접근 충돌 | **소유권 장벽(Barrier)** 및 일관성 프로토콜 적용 | 데이터 정합성 및 원자적 실행 보장 |
| 모듈 내부 로직 오류 | 타임아웃 감시 및 **소프트웨어 폴백(Fallback)** 구현 | 모듈 장애 시에도 시스템 가용성 유지 |

#### 한줄 요약
- 실무에서는 동적 비용 모델로 오프로드를 선별하고, CXL 일관성으로 충돌을 방어하며, 소프트웨어 폴백으로 장애를 격리한다.

## Ⅶ. 결론

- 축약률이 높고 복합 연산이면 **PNM**, 범용 제어면 호스트 처리 선택

#### 한줄 요약
- PNM은 표준 DRAM 생태계를 보존하면서 데이터 이동 병목을 해결하는 가장 현실적인 근접 컴퓨팅 솔루션이다.
