## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **메모리 근접 처리(Processing Near Memory, PNM)**: 메모리 모듈이나 컨트롤러 인근 로직에서 데이터를 처리해 호스트 전송량을 줄이는 구조.
- **왕복 전송량(Round-Trip Transfer Volume)**: 원본 데이터를 호스트로 가져오고 결과를 장치로 돌려보내며 링크를 오가는 데이터 양.

</details>

- 정의/개념: 메모리 모듈·컨트롤러의 인접 로직에서 데이터를 처리하는 **PNM** 구조
- 배경/필요성: 호스트 중심 처리는 대량 원본을 메모리 링크로 왕복시켜 전송 지연과 에너지 증가

#### 한줄 요약

- PNM은 메모리 인접 로직에서 원본을 처리하고 축약 결과만 반환해 왕복 전송량과 에너지를 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **로직 다이(Logic Die)**: 메모리와 같은 패키지에서 프로그래밍 가능한 디지털 연산을 수행하는 칩.
- **내부 대역폭(Internal Bandwidth)**: 메모리 채널•뱅크와 인접 로직 사이에서 장치 내부로 제공되는 전송량.
- **PNM DIMM(Processing Near Memory DIMM)**: 메모리 모듈의 버퍼 영역에 연산 로직을 배치한 근접 처리 장치.
- **메모리 인접 로직(Near-Memory Logic)**: 스캔•필터•압축•집계를 수행해 호스트로 반환할 데이터를 줄이는 회로.

</details>

- 다중 채널을 처리하는 **메모리 인접 로직**으로 호스트 전송량 절감
- 프로그래밍 가능한 **로직 다이**로 질의별 연산 변경 지원
- 모듈 버퍼 로직의 **PNM DIMM** 구현

#### 한줄 요약

- 메모리 인접 로직은 여러 채널의 데이터를 프로그래밍 가능한 연산으로 처리하고 축약 결과만 호스트에 반환한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **호스트 인터페이스(Host Interface)**: 작업 명령과 축약 결과가 호스트와 장치 사이를 오가는 연결 규약.
- **메모리 채널(Memory Channel)**: 인접 로직에 독립 데이터 전송 경로를 제공하는 구성요소.
- **메모리 뱅크(Memory Bank)**: 인접 로직에 셀 배열의 병렬 접근을 제공하는 구성요소.

</details>

```text
[호스트 인터페이스] -- [메모리 인접 로직] -- [메모리 장치]
```

선의 의미: 호스트 접점, 근접 연산 로직, 메모리 장치가 패키지•모듈 내부에서 결합된 정적 PNM 구조.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 인터페이스 | 명령 수신•축약 결과 반환 |
| 메모리 인접 로직 | 필터•압축•집계 수행 |
| 메모리 장치 | 채널•뱅크 **내부 대역폭** 공급 |

#### 한줄 요약

- 호스트 인터페이스가 작업을 받고 인접 로직이 메모리 장치의 데이터를 내부에서 처리한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **PNM 런타임(PNM Runtime)**: 작업 이관•버퍼 할당•완료•오류 처리를 관리하는 소프트웨어 계층.
- **결과 축약(Result Reduction)**: 원본보다 훨씬 작은 필터•압축•집계 결과만 생성하는 처리.
- **장애 격리(Fault Isolation)**: 장치 오류가 호스트 전체로 전파되지 않도록 실패 범위를 제한하는 설계.

</details>

```text
                    [호스트 후보 연산]
                            |
                1. 축약 이득•유연성 판정
                       /           \
                  [PNM 부적합]    [PNM 적합]
                       |              |
                 [호스트 실행]  2. 버퍼 소유권•명령 이관
                                      |
                    +-----------------------------+
                    | 반복: 할당된 채널•뱅크     |
                    | 3. 메모리 근접 연산         |
                    +-----------------------------+
                                      |
                           4. 축약•완료 상태 확정
                                      |
                              [결과•오류 반환]
```

### 동작 원리

1. **이관 적합성 판정**: 예상 축약량·연산 변경성·이관 지연을 비교해 PNM 실행 여부 결정.
2. **버퍼 소유권·명령 이관**: **PNM 런타임**이 호스트 접근을 동기화한 뒤 연산 종류와 데이터 범위를 장치에 전달.
3. **메모리 근접 연산**: 인접 로직이 여러 **메모리 채널**·**메모리 뱅크**의 원본을 필터·압축·집계.
4. **결과·완료 상태 반환**: **결과 축약**으로 만든 값과 장치 실행 오류를 호스트에 전달하고 버퍼 소유권 복귀.

#### 한줄 요약

- PNM은 동기화한 버퍼를 장치 내부에서 처리하고, 축약 결과와 완료 상태만 호스트 링크로 반환한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **메모리 내 처리(Processing-in-Memory, PIM)**: 메모리 셀이나 뱅크 내부에서 연산하는 방식.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 곱셈 결과를 누적 합계에 더하는 연산.
- **프로그래밍 가능 연산(Programmable Operation)**: 질의나 워크로드에 따라 로직이 수행할 기능을 바꿀 수 있는 특성.
- **연산 표현력(Operation Expressiveness)**: 지원할 수 있는 명령•분기•데이터 형식의 범위.
- **최단 이동(Shortest Movement)**: 데이터를 셀이나 뱅크 밖으로 거의 옮기지 않고 저장 위치에서 처리하는 목표.

</details>

| 연산 배치 위치 | PNM | PIM |
|:---|:---|:---|
| 적용 기준 | 질의마다 연산이 바뀔 때 | **MAC** 같은 고정 반복이 지배할 때 |
| 핵심 특징 | **로직 다이**의 **프로그래밍 가능 연산** | 셀•뱅크 내부의 **최단 이동** 처리 |
| 한계 | 호스트 왕복만 절감하는 이동 감소 폭 | 메모리 공정에 갇힌 **연산 표현력** |

> 요약: 연산 유연성을 우선하면 PNM, 이동 거리 단축을 우선하면 PIM.

#### 한줄 요약

- 질의별 연산 변경이 잦으면 PNM이 유리하고, 고정 반복 연산의 데이터 이동을 최소화하려면 PIM이 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **소유권 장벽(Ownership Barrier)**: 호스트와 장치가 같은 버퍼를 동시에 수정하지 못하게 하는 규칙.
- **완료 장벽(Completion Barrier)**: 장치 작업 완료 뒤 호스트 접근을 허용하는 순서 규칙.
- **타임아웃(Timeout)**: 장치 작업이 제한 시간 안에 끝나지 않으면 실패로 판정하는 절차.
- **재시도(Retry)**: 실패한 장치 작업을 다시 실행하는 복구 절차.
- **채널 편향(Channel Skew)**: 요청이 일부 메모리 채널에 몰려 내부 병렬성이 낮아지는 상태.
- **CXL(Compute Express Link)**: 프로세서와 메모리 장치를 일관성 있게 연결하는 규격.
- **일관성 규칙(Coherence Rule)**: 호스트와 장치가 공유 버퍼의 최신값과 접근 순서를 일치시키는 규칙.
- **채널별 큐 깊이(Per-Channel Queue Depth)**: 각 메모리 채널에서 처리 대기 중인 요청의 개수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 명령 설정·완료 대기 비용이 축약 이득 초과 | 원본·결과 크기와 실행 지연을 함께 비교 | 손익이 없는 비효율 이관 방지 |
| 호스트와 장치가 같은 버퍼를 수정해 데이터 경합 | **소유권 장벽**·**완료 장벽**·**일관성 규칙** 적용 | 실행 전후 순서 보장으로 오래된 읽기 방지 |
| 장치 로직이 완료되지 않거나 오류 반환으로 호스트 작업 정지 | **타임아웃**·**재시도**·**장애 격리** 적용 | 실패 범위 제한과 작업 복구 가능성 향상 |
| 요청 주소가 일부 채널에 몰려 **채널 편향** | 데이터 분할 재조정하고 **채널별 큐 깊이** 감시 | 유휴 채널 감소로 내부 병렬성 향상 |

> 사례: PNM 로직에서 스캔•압축을 먼저 수행하는 **CXL** 메모리 장치

#### 한줄 요약

- 장치 내부 축약으로 아낀 전송 비용이 이관 비용보다 클 때 PNM을 사용한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **연산 변경 빈도(Operation Change Frequency)**: 실행할 필터•압축•집계 기능이 워크로드마다 달라지는 정도.
- **연산 위치 선택 기준**: 연산 변경 빈도와 데이터 이동 거리로 PNM과 PIM을 고르는 기준.

</details>

- **연산 위치 선택 기준**에 따라 **연산 변경 빈도**가 높으면 **PNM**, 고정 반복과 **최단 이동**이 중요하면 **PIM** 선택

#### 한줄 요약

- 연산이 자주 바뀌면 PNM, 고정 연산의 데이터 이동 최소화가 중요하면 PIM이 적합하다.
