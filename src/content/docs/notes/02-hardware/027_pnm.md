## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리(Processing Near Memory, PNM)**: 메모리 셀 내부가 아닌 메모리 컨트롤러, 로직 다이 또는 DIMM/CXL 모듈 기판에 연산 유닛을 배치하여 호스트와 메모리 간 데이터 전송량을 절감하는 컴퓨팅 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 호스트 프로세서와 메모리 모듈 간에 시스템 버스를 통과하는 요청 및 원본 데이터의 전체 왕복 전송 패킷량.

</details>

- 정의/개념: 메모리 셀이 아니라 컨트롤러·로직 다이·모듈 쪽에 연산기를 두어 **왕복 전송량** 줄이는 **PNM**
- 배경/필요성: 셀 내부 연산은 메모리 공정 제약으로 단순 산술을 넘지 못하고, 원본을 호스트로 전부 옮기면 버스 병목 발생

#### 한줄 요약
- 연산기를 셀에서 한 걸음 물러난 자리에 둔 선택이 핵심이며, 그 한 걸음이 이동 절감량을 조금 포기하는 대신 논리 공정의 표현력을 통째로 얻어 온다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 표준 첨단 파운드리 CMOS 논리 공정으로 제조되어 복합 제어 및 산술·필터링·압축 연산을 고속 처리하는 가속 칩.
- **CXL 기반 PNM 모듈(Compute Express Link based PNM Module)**: CXL 프로토콜을 통해 호스트와 캐시 일관성 및 메모리 풀링을 지원하면서 근접 가속 연산을 수행하는 하드웨어 모듈.

</details>

- **로직 다이** 활용 표준 논리 공정으로 제조해 필터·압축·집계 같은 복합 연산까지 수용
- 표준 DRAM과 **CXL 기반 PNM 모듈** 형태를 유지해 기존 서버에 그대로 장착 가능
- 모듈 안에서 사전 필터링·집계를 끝내 호스트로 넘기는 원본 데이터량을 축소

#### 한줄 요약
- 특수 DRAM을 요구하지 않는다는 점이 성능 수치보다 중요한 강점이며, 도입 장벽이 낮아야 실제로 쓰인다는 사실을 설계에 반영한 결과다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(Host Interface)**: PCIe 또는 CXL 물리 계층을 통해 호스트 프로세서와 PNM 모듈 간의 제어 명령, 주소, 상태를 고속 전송하는 연결 인터페이스.
- **PNM 런타임(PNM Runtime)**: 호스트 운영체제 및 사용자 공간에서 실행되어 연산 오프로드 여부 판정, 메모리 동기화 장벽 제어, 예외 처리를 총괄하는 소프트웨어 계층.

</details>

```text
[PNM 시스템]
├─ 호스트 프로세서
│  └─ PNM 런타임 (오프로드 판정·동기화·예외 처리)
├─ 호스트 인터페이스 (CXL·PCIe)
└─ PNM 모듈
   ├─ 메모리 인접 로직 (스캔·필터·압축·집계)
   └─ 표준 DRAM 배열 (로컬 메모리 버스로 연결)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 호스트 인터페이스만이 모듈 경계를 넘고 나머지 대용량 전송은 모듈 안에서 끝남

| 구성요소 | 책임 |
|:---|:---|
| **호스트 인터페이스** | 오프로드 명령·결과·상태를 모듈 경계 너머로 중계 |
| 메모리 인접 로직 | 호스트 전송 전 스캔·필터링·압축·집계 수행 |
| 표준 DRAM 배열 | 대용량 원본 데이터 저장·다중 채널 접근 제공 |
| **PNM 런타임** | 오프로드 판정·동기화 장벽·예외 처리 관장 |

#### 한줄 요약
- 구성요소 넷 중 하나가 소프트웨어라는 점이 PNM의 성격을 드러내며, 어떤 연산을 언제 내려보낼지 판단하는 계층이 없으면 하드웨어만으로는 이득이 나지 않는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 근접 연산 수행 중 호스트 CPU와 PNM 연산기가 동일 버퍼에 동시 접근하여 발생하는 데이터 경쟁을 차단하는 메모리 동기화 장벽 메커니즘.

</details>

```text
호스트 근접 처리 요청
        │
   축약률이 전송·동기화 비용을 넘는가?
   ┌────┴─────┐
 아니오        예
   │            │
호스트가       대상 버퍼 소유권 이전
직접 읽기      (캐시 정리·장벽 설정)
   │            │
   │      메모리 인접 로직이 스캔·필터·압축·집계
   │            │
   │       결과 축약 후 완료 확정
   │            │
   └────┬───────┘
        │
  호스트가 결과 소비·소유권 복귀
```

분기 결과: 축약률이 낮으면 판정 단계에서 곧바로 반려되어 호스트가 직접 읽는 편이 빠르고, 통과한 경우에만 **소유권 장벽** 설정과 결과 확정이라는 동기화 비용을 추가로 지불

#### 한줄 요약
- 판정 단계가 흐름의 맨 앞에 있다는 사실이 중요하며, 오프로드가 항상 이득이 아니라는 전제를 하드웨어 흐름 자체가 인정하고 있다.

## Ⅴ. 종류 및 비교

| 연산 위치 | PNM | PIM | 호스트 중심 |
|:---|:---|:---|:---|
| 적용 기준 | DB 필터링·압축처럼 모듈 수준 오프로드가 가능 | AI 행렬 곱셈처럼 이동 절감이 절대적 | 복잡한 제어 로직과 범용 스칼라 연산 |
| 핵심 특징 | 컨트롤러·로직 다이에 연산기·표준 DRAM 활용 | 셀·배열·뱅크 가까이의 연산기·높은 내부 대역폭 | 호스트 코어의 유연한 범용 연산 |
| 한계 | 칩↔컨트롤러 물리 버스 잔여 오버헤드 | 메모리 공정 제약·복잡한 로직 탑재 곤란 | 외부 버스 병목·이동 전력 낭비 |

#### 한줄 요약
- 세 위치는 연산기를 데이터에서 얼마나 멀리 둘지를 눈금으로 놓은 같은 축이며, 가까울수록 이동은 줄지만 만들 수 있는 연산기는 단순해진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장애 격리(Fault Isolation)**: PNM 모듈 내부 연산기에서 예외, 하드웨어 오류 또는 타임아웃 발생 시 호스트 시스템 전체 패닉으로 번지지 않도록 소프트웨어 폴백으로 전환하는 신뢰성 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근접 처리 지연이 단순 읽기 지연 초과 | 축약률·전송 비용 비교 후 선별 오프로드 | 소용량 작업의 불필요한 이관 감소 |
| 호스트와 PNM이 동일 버퍼에 동시 접근 | **소유권 장벽**·캐시 일관성·완료 동기화 | 데이터 관찰 순서 보장 |
| PNM 로직 오류로 시스템 장애 확산 | 타임아웃·오류 보고·소프트웨어 **장애 격리** | 국소 오류 영향 범위·복구 시간 감소 |
| 특정 채널 집중으로 연산 병렬성 저하 | 컨트롤러 수준 주소 인터리빙·큐 깊이 모니터링 | 다중 채널 병렬 처리율·대역폭 극대화 |

#### 한줄 요약
- 네 대책 중 둘이 신뢰성 문제인 이유는 연산기가 메모리 경로 안으로 들어오면서 오류가 데이터 손상으로 직결되기 때문이며, 가속기와 달리 **장애 격리** 활용 선택 사항으로 둘 수 없다.

## Ⅶ. 결론

- 기존 메모리·호스트 인터페이스 호환성과 복합 연산이 중요하면 **PNM** 우선하고, 연산이 단순·고정되며 이동 절감 효과가 충분히 크면 PIM으로 더 가깝게 배치

#### 한줄 요약
- PNM이 PIM보다 먼저 상용화된 이유는 성능이 아니라 기존 서버를 바꾸지 않아도 된다는 점이며, 근접 가속에서는 도입 가능성이 최대 성능을 이긴다.
