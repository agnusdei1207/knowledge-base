## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 근접 처리(Processing Near Memory, PNM)**: DRAM 셀 내부가 아닌 메모리 컨트롤러, 로직 다이 또는 DIMM/CXL 모듈 기판에 연산 유닛을 배치하여 표준 상용 DRAM을 그대로 활용하면서 호스트-메모리 간 전송량을 획기적으로 줄이는 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 호스트 프로세서와 메모리 모듈 간의 시스템 버스를 통과하는 요청 및 대규모 원본 데이터의 전체 패킷 트래픽.

</details>

- 정의/개념: 메모리 셀 내부가 아닌 메모리 컨트롤러·인터페이스 모듈(CXL/DIMM)에 연산 가속기를 배치하여 표준 DRAM 생태계를 유지하면서 **왕복 전송량**을 대폭 절감하는 **PNM(Processing Near Memory) 아키텍처**
- 배경/필요성: DRAM 공정의 로직 집적 한계(PIM의 제조 난이도)와 시스템 버스 대역폭 병목을 **상용 DRAM 호환성과 복합 연산 가속의 절충으로 해결**

#### 한줄 요약
- PNM은 표준 DRAM 모듈/CXL 컨트롤러에 연산기를 배치하여 제조 난이도를 낮추고 데이터 이동을 줄이는 실용적 근접 컴퓨팅 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 표준 첨단 파운드리 CMOS 공정으로 제조되어 복합 제어, 데이터 필터링, 압축, 해시 연산 등을 고속 처리할 수 있는 전용 가속 칩.
- **CXL 기반 PNM 모듈**: CXL.mem 및 CXL.io 프로토콜을 통해 표준 서버 슬롯에 장착되어 캐시 일관성 및 메모리 확장을 지원하면서 근접 연산을 수행하는 하드웨어 장치.

</details>

- 표준 DRAM 공정 활용: 특수 DRAM 공정이 필요한 PIM과 달리 **표준 상용 DRAM 칩**을 그대로 사용하므로 제조 비용 및 수율 측면에서 매우 유리
- 복합 연산 지원: 첨단 CMOS **로직 다이(Logic Die)**를 컨트롤러에 탑재하여 단순 산술을 넘어 DB 필터링, 정렬, 압축, 암호화 등 복합 연산 수행 가능
- 호환성 및 확장성: **CXL 기반 PNM 모듈** 형태로 제작되어 기존 서버의 PCIe/CXL 슬롯에 무수정 장착 가능

#### 한줄 요약
- 표준 DRAM을 변경 없이 그대로 쓰면서 컨트롤러의 로직 다이에서 복합 연산을 처리하므로 상용화와 호환성이 뛰어나다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스(Host Interface)**: PCIe/CXL 물리 계층을 통해 호스트 CPU와 PNM 모듈 간의 제어 명령 및 요약 결과를 고속 통신하는 인터페이스.
- **PNM 런타임(PNM Runtime)**: OS 및 사용자 계층에서 실행되어 워크로드 오프로딩 여부를 동적으로 판별하고 메모리 동기화 장벽을 제어하는 소프트웨어 계층.

</details>

```text
[호스트 CPU 서버] ── [PNM 소프트웨어 런타임 (오프로드 판정 및 동기화)]
        │
        ▼ (CXL / PCIe 고속 직렬 링크)
[CXL 기반 PNM 모듈 (CXL-PNM Card / Smart DIMM)]
 ├─ [PNM 컨트롤러 & 가속 로직 다이 (Logic Die)]
 │   ├─ CXL.io / CXL.mem 프로토콜 엔진
 │   ├─ 가속 연산 코어 (스캔, 필터링, 압축, 집계 유닛)
 │   └─ 다채널 로컬 메모리 제어기 (Local MC)
 │
 └─ [표준 상용 DRAM 어레이 (Standard DDR4/DDR5 DRAM Chips)]
     ├─ DRAM 채널 0 (표준 모듈)
     └─ DRAM 채널 1 (표준 모듈)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 호스트와 모듈 간은 CXL로 연결되고, 모듈 내부는 표준 DRAM 채널로 직결됨

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **호스트 CPU & 런타임**| 서버 호스트 계층 | 데이터 오프로드 스케줄링 및 **PNM 런타임** 기반 동기화 | 커널 드라이버 연동 |
| **호스트 인터페이스** | 모듈 연결부 | CXL.io / CXL.mem 프로토콜 기반 고속 패킷 송수신 | PCIe/CXL 물리 계층 |
| **PNM 로직 다이** | PNM 모듈 기판 실장 | 데이터 스캔, 필터링, 압축, 해시 집계 등 복합 가속 연산 | 표준 CMOS 파운드리 제조 |
| **표준 DRAM 어레이** | PNM 모듈 기판 실장 | 대용량 데이터 저장 및 다채널 로컬 대역폭 제공 | 표준 상용 DRAM 칩 사용 |

#### 한줄 요약
- PNM 시스템은 호스트 런타임, CXL 인터페이스, PNM 로직 다이, 표준 상용 DRAM 칩의 4단계 계층으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 근접 연산 수행 중 호스트와 PNM 컨트롤러가 동일 버퍼에 동시 접근하여 발생하는 데이터 충돌을 방지하는 동기화 장벽.

</details>

```text
1. 호스트 애플리케이션의 대규모 데이터 처리(DB Table Scan 등) 요청
                      │
                      ▼
2. PNM 런타임: 데이터 축약률이 오프로딩 오버헤드보다 큰지 판정
   ┌──────────────────┴──────────────────┐
[ 축약률 낮음 (오프로드 비효율) ]     [ 축약률 높음 (오프로드 유리) ]
   │                                     │
   ▼                                     ▼
호스트 CPU가 메모리 직접 읽기         3. 대상 메모리 버퍼 소유권 이전 및 동기화 장벽 설정
   │                                     │
   │                                     ▼
   │                              4. PNM 로직 다이가 표준 DRAM에서 데이터를 고속 인출
   │                                     │
   │                                     ▼
   │                              5. 모듈 내부에서 스캔·필터링·압축 연산 수행
   │                                     │
   │                                     ▼
   │                              6. 필터링된 최소 결과만 CXL 링크로 호스트에 반환
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 호스트 프로세서가 최종 결과 수신 및 소유권 복귀
```

분기 결과: **축약률이 높을 때만** 모듈 내부 연산을 수행하여 시스템 버스 트래픽을 90% 이상 절감하고, **단순 읽기는** 직접 처리함

#### 한줄 요약
- 런타임이 축약률을 평가하여 유리할 때만 모듈 로직 다이로 연산을 오프로딩하고 필터링된 결과만 호스트에 반환한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 메모리 근접 처리 (PNM) | 메모리 내 처리 (PIM) | 호스트 중심 처리 (Host-Centric) |
|:---|:---|:---|:---|
| 연산 위치 | **컨트롤러 / CXL 모듈 기판 로직 다이** | **DRAM 셀 / 뱅크 내부 직접 집적** | **호스트 CPU / GPU 코어** |
| 사용 메모리 | **표준 상용 DRAM (DDR4/DDR5/LPDDR)** | 특수 맞춤형 DRAM (공정 변경 필수) | 표준 시스템 메모리 (DDR/HBM) |
| 지원 연산 범위 | **복합 연산 (DB 스캔, 필터링, 정렬, 압축)**| 단순 연산 (MAC, 벡터 덧셈, 활성화) | **모든 범용 복합 연산 및 제어** |
| 제조 난이도 및 비용| **낮음 (기존 파운드리 및 표준 DRAM 결합)** | 높음 (DRAM 내 로직 집적으로 수율 저하) | 낮음 (기존 구조) |
| 주요 적용 분야 | **데이터베이스 검색 가속, 그래프 분석, 빅데이터** | **AI 딥러닝 추론, LLM 어텐션 연산 가속** | 범용 OS, 복합 비즈니스 로직 |

#### 한줄 요약
- 복합 데이터 필터링과 호환성에는 PNM이 적합하고, 단순 대규모 행렬 연산에는 PIM이, 범용 제어에는 호스트 중심 처리가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장애 격리(Fault Isolation)**: PNM 모듈 내부 연산기 오류나 타임아웃 발생 시 호스트 커널 패닉을 방지하고 소프트웨어 폴백으로 전환하는 신뢰성 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 축약률이 낮은 단순 작업 오프로딩 시 오히려 지연시간 증가 | **런타임 비용 모델 기반 동적 오프로딩 판정 엔진** 탑재 | 손익분기점 이상의 작업만 선별 처리 |
| 호스트와 PNM 모듈이 동일 메모리 영역을 동시 접근하여 충돌 | **CXL.cache 일관성 프로토콜 및 소유권 장벽(Barrier)** 적용 | 데이터 정합성 및 원자적 실행 보장 |
| PNM 모듈 내부 로직 오류 시 시스템 전체 다운 위험 | **타임아웃 감시 및 소프트웨어 폴백(Fallback) 장애 격리** | 모듈 장애 시에도 시스템 가용성 유지 |

#### 한줄 요약
- 실무에서는 동적 비용 모델로 오프로드를 선별하고, CXL 일관성으로 충돌을 방어하며, 소프트웨어 폴백으로 장애를 격리한다.

## Ⅶ. 결론

- 빅데이터 및 인메모리 데이터베이스 가속을 위해 **표준 상용 DRAM과 첨단 로직 다이를 CXL 인터페이스로 결합한 PNM(Processing Near Memory) 아키텍처를 도입**하고, 소프트웨어 계층에서는 **비용 모델 기반의 지능형 오프로딩 런타임**을 구축하며, 대규모 확장 시 **CXL 메모리 풀링과 연계**하는 실용적 근접 가속 시스템 확립

#### 한줄 요약
- PNM은 표준 DRAM 생태계를 보존하면서 데이터 이동 병목을 해결하는 가장 현실적인 근접 컴퓨팅 솔루션이다.
