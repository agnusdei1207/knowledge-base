## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PNM(Processing Near Memory)**: 메모리 셀에서 분리된 컨트롤러·베이스 로직 다이·모듈 근처에 연산 유닛을 배치해 호스트 왕복 데이터량을 줄이는 가속 아키텍처.
- **왕복 전송량(Round-Trip Traffic)**: 프로세서와 메모리 버스 사이를 오가는 원본 데이터 읽기·쓰기 패킷의 총량; 줄일수록 지연·에너지 절감.

</details>

- 정의/개념: 컨트롤러·베이스 로직 다이·메모리 모듈 근처에 연산 유닛을 배치해 **왕복 전송량**을 줄이는 가속 아키텍처
- 배경/필요성: 메모리 공정 변경 없이 표준 DRAM을 활용하면서 DB 스캔·필터링 등 복잡한 연산의 유연성과 시스템 호환성 확보

#### 한줄 요약
- 표준 메모리 주변 로직 다이와 컨트롤러에 연산기를 배치해 유연한 데이터 오프로딩을 구현하는 아키텍처다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로직 다이(Logic Die)**: 첨단 파운드리 논리 공정으로 제조되어 복합 산술·필터링·압축을 고속 처리하는 가속 칩; 메모리 공정 제약을 받는 PIM과 대비.
- **CXL 기반 PNM 모듈**: CXL 연결을 사용해 메모리 확장·가속 기능을 제공하도록 설계한 근접 처리 모듈; 표준 서버 호환.

</details>

- **로직 다이**(ASIC/FPGA)에 표준 논리 공정 적용으로 복합 분기·부동소수점 등 다양한 연산 유연성 지원
- 표준 DRAM 칩을 그대로 활용해 기존 서버 마더보드·**CXL 인터페이스**와의 높은 시스템 호환성 보장
- **메모리 인접 로직**으로 호스트 CPU 전송 전 스캔·필터링·집계 축약을 자체 수행해 원본 이동 최소화

#### 한줄 요약
- 표준 DRAM 칩을 그대로 활용하면서 로직 공정 기반의 고도화된 연산 표현력을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 인터페이스**: PCIe 또는 CXL 연결로 호스트와 모듈 사이의 명령·데이터·상태를 전달하는 경로.
- **PNM 런타임**: 호스트 OS에서 실행해 연산 오프로드 판정·메모리 동기화 장벽·예외 처리를 관장하는 소프트웨어 계층.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 호스트 프로세서 (Host CPU / DB Query Engine)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │  [ CXL / PCIe 고속 상호 연결 버스 ]
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ PNM 모듈 (CXL Type-2/3 스마트 기판)                          │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 모듈 컨트롤러 및 인접 연산 로직 (ASIC / FPGA)          │  │
│  │  └─ DB Scan / Filter / Sort / Compression Engine      │  │
│  └───────────────────────────┬───────────────────────────┘  │
│                              │  [ 다중 채널 로컬 메모리 버스 ] │
│  ┌───────────────────────────┴───────────────────────────┐  │
│  │ 표준 상용 DRAM 칩 배열 (DDR5 / LPDDR5 Components)     │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: `→` CXL/PCIe는 호스트↔PNM 명령·결과 전달; 로컬 메모리 버스는 모듈 컨트롤러↔DRAM 대용량 데이터 전달

| 구성요소 | 책임 |
|:---|:---|
| 호스트 인터페이스 | 프로세서↔모듈 간 오프로드 명령·데이터·상태 통신 중계 |
| 메모리 인접 로직 | 호스트 전송 전 스캔·필터링·압축·집계 수행 |
| 표준 DRAM 배열 | 대용량 원본 데이터 저장·다중 채널 접근 제공 |
| PNM 런타임 | 소유권 장벽·오프로드 스케줄링·장애 격리 관리 |

#### 한줄 요약
- 호스트 인터페이스(CXL)·PNM 모듈 컨트롤러(연산 로직)·표준 DRAM 배열이 통합된 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소유권 장벽(Ownership Barrier)**: 연산 실행 중 호스트 CPU와 PNM 로직이 동일 버퍼에 동시 쓰기하지 못하도록 차단하는 동기화 펜스.

</details>

```text
호스트 DB 테이블 스캔 쿼리 발생
      │
      ▼
1. 오프로드 판정 및 명령 발송
      │
      ▼
2. 메모리 영역 소유권 장벽 설정
      │
      ▼
3. PNM 컨트롤러: 로컬 채널에서 대용량 데이터 인출·필터링
      │
      ▼
4. 유효 조건 데이터 추출·결과 축약
      │
      ▼
5. 축약 결과만 호스트 반환·장벽 해제
```

**동작 원리**

1. **오프로드 판정**: 호스트 런타임이 데이터 크기·필터 조건을 분석해 PNM 오프로드 결정
2. **소유권 분리**: 대상 메모리 영역에 CPU 캐시 플러시 및 **소유권 장벽** 설정
3. **근접 연산**: 모듈 컨트롤러가 로컬 DRAM에서 수십 GB 데이터를 고속 인출해 조건 대조·필터링
4. **결과 축약**: 필터링 통과 레코드만 선별해 호스트 반환 버퍼 적재
5. **완료 통보**: 완료 인터럽트를 호스트로 전송·소유권 장벽 해제

#### 한줄 요약
- 오프로드 판정 후 소유권 장벽 설정 → 근접 스캔·필터링 → 결과 축약 반환 순서로 동작한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | PNM | PIM | 호스트 중심 |
|:---|:---|:---|:---|
| 적용 기준 | DB 필터링·압축 등 **모듈 수준** 오프로드 | AI 행렬 곱셈 등 **데이터 이동 최소화** 필수 | 복잡한 제어 로직·범용 스칼라 연산 |
| 핵심 특징 | 컨트롤러·로직 다이에 연산기·표준 DRAM 호환 | 메모리 뱅크 내부 단순 연산기·초광폭 대역폭 | 호스트 코어의 유연한 범용 연산 |
| 한계 | 칩↔컨트롤러 물리 버스 잔여 오버헤드 | 메모리 공정 제약·복잡한 로직 탑재 곤란 | 외부 버스 병목·이동 전력 낭비 |

#### 한줄 요약
- PNM은 표준 칩 호환성과 연산 유연성, PIM은 극단적 이동 절감, 호스트는 범용 제어가 강점이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **장애 격리(Fault Isolation)**: PNM 모듈 내부 연산기 예외·타임아웃 발생 시 호스트 패닉을 방지하고 소프트웨어 폴백으로 전환하는 신뢰성 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근접 처리 지연이 단순 읽기 지연 초과 | 축약률·전송 비용 비교 후 선별 오프로드 | 소용량 작업의 불필요한 이관 감소 |
| 호스트와 PNM이 동일 버퍼에 동시 접근 | **소유권 장벽**·캐시 일관성·완료 동기화 | 데이터 관찰 순서 보장 |
| PNM 로직 오류로 시스템 장애 확산 | 타임아웃·오류 보고·소프트웨어 **장애 격리** | 국소 오류 영향 범위·복구 시간 감소 |
| 특정 채널 집중으로 연산 병렬성 저하 | 컨트롤러 수준 주소 인터리빙·큐 깊이 모니터링 | 다중 채널 병렬 처리율·대역폭 극대화 |

#### 한줄 요약
- 축약률 동적 비교·소유권 장벽·장애 격리·주소 인터리빙으로 PNM 성능과 신뢰성을 확보한다.

## Ⅶ. 결론

- 데이터 이동 대비 **축약 효과**가 큰 복잡한 쿼리·그래프·필터링 작업에 **PNM**을 검토하되, 연결 규격·일관성 모델·프로그래밍 환경·장애 처리 체계를 확인해 채택

#### 한줄 요약
- 연산 복잡도와 인프라 호환성을 함께 고려해 실용적 근접 가속 솔루션을 구축해야 한다.
