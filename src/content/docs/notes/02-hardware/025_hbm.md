## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **고대역폭 메모리(High Bandwidth Memory, HBM)**: DRAM 다이를 TSV로 수직 적층하고 로직 다이와 광폭 인터페이스로 연결한 고대역폭 패키지 메모리.
- **메모리 벽(Memory Wall)**: 프로세서 연산 속도에 비해 메모리 데이터 공급 대역폭이 부족해 성능이 제한되는 현상; AI·HPC 병목의 주원인.
- **실리콘 인터포저(Silicon Interposer)**: 로직 다이와 HBM 스택 사이에 고밀도 배선을 제공하는 패키지 기판.

</details>

- 정의/개념: DRAM 다이를 수직 적층하고 **실리콘 인터포저**로 가속기와 직결한 **고대역폭 메모리(High Bandwidth Memory, HBM)**
- 배경/필요성: 연산 성능이 메모리 공급 속도보다 빠르게 증가해 **메모리 벽**이 가속기 활용률을 직접 제한

#### 한줄 요약
- HBM이 푸는 문제는 메모리가 느리다는 것이 아니라 배선을 낼 자리가 없다는 것이며, 그래서 해법이 소자가 아니라 패키징에서 나왔다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **실리콘 관통 전극(Through-Silicon Via, TSV)**: 다이를 수직으로 관통해 상하 칩의 전기 신호를 연결하는 배선; HBM 적층의 핵심 기술.
- **광폭 인터페이스(Wide Interface)**: 수천 개의 데이터 선을 병렬로 사용해 핀당 속도를 낮추고 전체 대역폭을 높이는 인터페이스.
- **채널 인터리빙(Channel Interleaving)**: 메모리 요청을 여러 독립 채널에 분산해 병렬 전송을 극대화하는 방식.

</details>

- **TSV** 수직 적층으로 다이 간 배선 길이를 단축하여 신호 지연 및 에너지 소모 절감
- **광폭 인터페이스**로 핀당 속도를 낮추면서 전체 메모리 대역폭 확대
- **채널 인터리빙**을 통한 요청 병렬 분산으로 유효 대역폭 극대화

#### 한줄 요약
- 핀당 속도를 낮추고 선 수를 늘린 선택이 신호 무결성과 전력 문제를 동시에 완화하므로, 넓고 느린 쪽이 좁고 빠른 쪽보다 에너지 효율에서 앞선다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **베이스 다이(Base Die)**: HBM 스택 하단에서 DRAM 다이와 외부 로직 사이의 신호·명령 연결을 담당하는 인터페이스 다이.
- **마이크로범프(Microbump)**: 다이와 인터포저 사이의 전기적·기계적 연결을 위한 미세 접합부.
- **DRAM 코어 다이(DRAM Core Die)**: 실제 메모리 셀 배열을 포함하는 HBM 적층 다이.

</details>

```text
[가속기 패키지]
AI·GPU 로직 다이 ─ 마이크로범프 ─ 실리콘 인터포저 ─ 마이크로범프 ─ HBM 스택
                                                                     ├─ DRAM 코어 다이 × N
                                                                     │     ↕ TSV
                                                                     └─ 베이스 다이
```

선의 의미: `─`는 로직 다이와 HBM의 광폭 수평 연결, `↕`는 적층 다이 사이의 TSV 수직 연결

| 구성요소 | 책임 |
|:---|:---|
| 로직 다이 | 메모리 요청 발생과 가속 연산 수행 |
| **실리콘 인터포저** | **마이크로범프**를 통한 로직·HBM 간 광폭 배선 제공 |
| **DRAM 코어 다이** | 적층 단수만큼의 대용량 데이터 저장 |
| **TSV** | 적층 다이 간 수직 고밀도 신호 전달 |
| **베이스 다이** | 외부 인터페이스 수신과 **채널 인터리빙** 분산 |

#### 한줄 요약
- 모든 구성요소가 한 패키지에 봉인되므로 한 다이의 결함이 패키지 전체를 폐기시키며, HBM 원가의 상당 부분이 성능이 아니라 이 수율 위험에서 나온다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **메모리 컨트롤러(Memory Controller)**: 가속기 메모리 요청을 채널·뱅크에 배치하는 제어기.
- **버스트 전송(Burst Transfer)**: 연속 데이터를 한 명령으로 묶어 광폭 인터페이스로 전송하는 방식.

</details>

```text
가속기 메모리 요청
      │
      ▼
메모리 컨트롤러: 주소 분산 후 채널·뱅크 병렬 요청 생성
      │
      ▼
광폭 명령·주소 전달: 인터포저 경유 베이스 다이 도달
      │
      ▼
TSV 수직 전송: DRAM 코어 다이 접근 후 버스트 전송 반환
      │
      ▼
가속기 연산 유닛으로 데이터 공급
```

분기 결과: 요청이 여러 채널에 고르게 흩어지면 **버스트 전송**이 겹쳐 대역폭이 그대로 나오지만, 한 채널로 몰리면 광폭 배선이 있어도 그 채널 속도 이상은 나오지 않음

#### 한줄 요약
- 광폭 인터페이스의 대역폭은 요청이 흩어져 있을 때만 실현되는 잠재값이라, 데이터 배치가 나쁘면 비싼 패키징이 그대로 낭비된다.

## Ⅴ. 종류 및 비교

| 메모리 유형 | HBM | GDDR | DDR |
|:---|:---|:---|:---|
| 적용 기준 | 가속기·HPC에서 대역폭이 최우선 | 그래픽에서 대역폭과 비용의 균형 | 범용 시스템의 용량·확장성 우선 |
| 핵심 특징 | 적층 DRAM·**광폭 인터페이스**·낮은 핀 전력 | 협폭 고속 인터페이스·GDDR 세대 향상 | DIMM 기반 범용 확장성 |
| 한계 | 패키징·열·비용 부담 | 신호 전력·공간 제약 | 가속기 대역폭 병목 가능 |

#### 한줄 요약
- 세 메모리는 성능 등급이 아니라 용량을 늘리는 방식이 갈리며, HBM만은 패키지에 봉인돼 나중에 증설할 수 없다는 점이 결정적 제약이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **양품 다이(Known Good Die, KGD)**: 적층 전 시험을 통과해 정상 동작이 확인된 다이; 적층 수율 핵심.
- **직접 칩 냉각(Direct-to-Chip Liquid Cooling)**: 냉각판·냉각 유체로 고밀도 패키지의 열을 직접 제거하는 방식.
- **메모리 RAS(Reliability, Availability, Serviceability)**: 오류 검출·격리·복구를 포함하는 시스템 신뢰성 설계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적층 다이 결함으로 패키지 수율 저하 | **KGD** 선별·적층 전후 시험 | 결함 조기 검출·수율 향상 |
| 가속기+HBM 집중 발열 | 패키지 열 설계·**직접 칩 냉각** 검토 | 열 제한·성능 저하 완화 |
| 특정 채널 요청 쏠림 | **채널 인터리빙**·주소 배치 조정 | 유효 대역폭 향상 |
| 적층 연결부·셀 오류로 무결성 저하 | ECC와 **메모리 RAS** 기능 보장 범위 검증 | 검출·정정 가능 오류 범위 확정 |

#### 한줄 요약
- 네 문제 중 셋이 다이를 쌓았기 때문에 생기므로, 적층이 만든 대역폭 이득은 수율·발열·검증 비용으로 상당 부분 되돌려 준다.

## Ⅶ. 결론

- 실측 성능이 메모리 대역폭에 묶이고 패키지·열·용량 비용을 감당할 수 있을 때 **고대역폭 메모리(High Bandwidth Memory, HBM)**를 선택하며, 비용과 사후 증설이 우선이면 GDDR·DDR 유지

#### 한줄 요약
- HBM 채택 판단의 실제 기준은 대역폭 수치가 아니라 그 대역폭을 다 쓰는 워크로드가 있느냐이며, 못 쓰면 GDDR 대비 지불한 값이 전부 손실이다.
