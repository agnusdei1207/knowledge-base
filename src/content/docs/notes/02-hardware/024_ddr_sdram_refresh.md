## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **두 배 데이터율 동기식 동적 임의 접근 메모리(Double Data Rate Synchronous Dynamic Random-Access Memory, DDR SDRAM)**: 클록 상승•하강 엣지에서 데이터를 전송하고 주기적으로 전하를 복원하는 메모리이다.
- **동적 임의 접근 메모리(Dynamic Random-Access Memory, DRAM)**: 셀 전하로 비트를 저장해 주기적인 복원이 필요한 휘발성 메모리이다.
- **전하 누설**: DRAM 셀의 저장 전하가 시간이 지나며 줄어 데이터 보존을 위해 복원이 필요한 현상이다.

</details>

- 정의/개념: 클록의 상승·하강 엣지에서 데이터를 전송하고 셀 전하를 주기적으로 복원하는 **동기식 DRAM 규격**이다.
- 배경/필요성: 핀당 데이터 전송률을 높이면서 누설되는 셀 전하를 보존하기 위해 **양 엣지 전송·리프레시를 필요로 한다**.

#### 한줄 요약

- DDR은 양 에지 전송으로 대역폭을 높이고 리프레시로 누설 전하를 복원한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **양 엣지 전송**: 한 클록 주기의 상승과 하강 순간 모두에 데이터를 전달하는 방식이다.
- **뱅크 병렬성**: 독립 셀 배열과 행 버퍼를 가진 여러 뱅크가 접근을 겹쳐 수행하는 성질이다.
- **버스트 전송**: 열 명령 한 번으로 연속 데이터를 여러 엣지에 걸쳐 보내는 방식이다.
- **리프레시**: 누설되는 셀 전하를 보충하기 위해 메모리 행을 주기적으로 읽고 복원하는 동작이다.

</details>

- 같은 I/O 클록의 **상승·하강 엣지 전송**으로 단일 에지 방식보다 핀당 전송률 향상이 핵심이다.
- **뱅크 병렬성·버스트 전송**으로 행 처리와 데이터 전송을 겹쳐 연속 처리량을 확대한다.
- 누설 전하를 메우는 주기적 **리프레시** 강제가 핵심이다.

#### 한줄 요약

- DDR은 양 에지 전송과 뱅크 병렬성으로 처리량을 높이지만, 리프레시 동안 일부 또는 전체 접근이 제한된다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **메모리 컨트롤러**: 주소를 채널•랭크•뱅크•행•열로 나누고 접근과 리프레시 순서를 조정하는 회로이다.
- **두 배 데이터율 물리 계층(Double Data Rate Physical Layer, DDR PHY)**: 컨트롤러 명령과 데이터를 메모리 버스의 전기 신호로 변환하는 회로이다.
- **데이터 입출력(Data Input/Output, DQ)**: 실제 데이터 비트를 운반하는 신호이다.
- **데이터 스트로브(Data Strobe, DQS)**: 수신기의 데이터 샘플링 시점을 알리는 신호이다.
- **행 버퍼**: 활성화한 행 전체를 보관하며 감지와 복원을 수행하는 회로이다.

</details>

```text
[메모리 컨트롤러] -- [DDR 채널•PHY] -- [뱅크•행 버퍼]
                                               |
                                               |
                                      [리프레시 카운터]
```

선의 의미: 컨트롤러와 PHY는 뱅크 데이터 경로에 결합되고, 리프레시 카운터는 뱅크•행 버퍼의 갱신 주소를 제공하는 정적 연결이다.

| 구성요소 | 책임 |
|:---|:---|
| 메모리 컨트롤러 | 주소 매핑•**명령 순서** 조정 |
| DDR 채널•PHY | 명령•DQ•DQS **신호 변환** |
| 뱅크•행 버퍼 | 행•열 접근과 **전하 복원** |
| 리프레시 카운터 | 갱신 대상 **행 순환 지정** |

#### 한줄 요약

- 컨트롤러와 PHY가 명령을 전달하고 뱅크와 카운터가 데이터 접근과 전하 복원을 수행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **행 활성(Activate, ACT)**: 대상 DRAM 행을 여는 DDR 명령이다.
- **프리차지(Precharge, PRE)**: 다음 행 접근 전에 현재 행을 닫는 DDR 명령이다.
- **리프레시 간격(Refresh Interval, tREFI)**: 연속 리프레시 명령 사이에 허용되는 평균 시간 간격이다.
- **리프레시 주기 시간(Refresh Cycle Time, tRFC)**: 리프레시 수행으로 메모리 접근이 제한되는 시간이다.

</details>

```text
                    [DDR 요청 대기열]
                            |
                  1. tREFI 기한 판정
                      /           \
                  [여유]          [도래]
                    |               |
          2. ACT•행 버퍼 활성   4. 리프레시 범위 선택
                    |               |
          3. 열 선택•버스트 전송  5. 대상 행 전하 복원
                    |               |
               [행 유지?]      [tRFC 완료]
                /       \           |
              [예]      [아니요]     |
               |          |          |
          [열 접근 지속] [PRE]       |
               |          |          |
               +----+-----+----------+
                    |
              [다음 요청 처리]
```

**동작 원리**

1. **리프레시 기한 판정**: tREFI 허용 범위 안에서 일반 접근과 리프레시 명령의 실행 순서를 결정한다.
2. **행 버퍼 활성화**: 일반 접근이면 ACT 명령으로 대상 행을 감지 증폭기에 연결한다.
3. **열 선택·버스트 전송**: 활성 행의 열 데이터를 선택해 DQ·DQS 신호로 양 엣지를 전송한다.
4. **리프레시 범위 선택**: 기한이 도래하면 지원 방식에 따라 전체 뱅크 또는 특정 뱅크를 갱신 대상으로 지정한다.
5. **셀 전하 복원**: tRFC 동안 대상 행을 읽고 다시 기록해 누설된 전하를 보충한다.

#### 한줄 요약

- 메모리 컨트롤러는 tREFI 기한을 지키면서 일반 요청과 리프레시를 배치해 데이터 보존과 접근 지연을 절충한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **전체 뱅크 리프레시**: 명령 하나로 랭크의 모든 뱅크를 함께 갱신하는 방식이다.
- **뱅크별 리프레시**: 대상 뱅크만 갱신하고 나머지 뱅크의 접근을 허용하는 방식이다.
- **자체 리프레시**: 절전 상태에서 메모리가 내부 타이머로 스스로 전하를 복원하는 방식이다.

</details>

| 리프레시 방식 | 전체 뱅크 | 뱅크별 | 자체 리프레시 |
|:---|:---|:---|:---|
| 적용 기준 | 메모리 **접근이 한산한 구간** | **지연 민감 요청**이 지속되는 구간 | 외부 접근이 없는 **절전 대기**로 진입할 때 |
| 핵심 특징 | 명령 하나로 **전 뱅크 동시** 갱신 | 대상 **뱅크만 선택** 갱신 | **내부 타이머** 기반 자율 갱신 |
| 한계 | **tRFC** 동안 랭크 전체 차단 | 갱신 횟수 증가로 명령 대역 소모 | 외부 접근 **전면 차단** |

> 요약: 뱅크별 리프레시는 전체 갱신의 **랭크 차단 범위**를 특정 뱅크로 축소한다.

#### 한줄 요약

- 전체 뱅크 방식은 제어가 단순하고, 뱅크별 방식은 접근 차단 범위를 줄이며, 자체 방식은 절전 중 데이터만 보존한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **꼬리 지연**: 일부 요청이 리프레시 차단과 겹쳐 평균보다 크게 늦어지는 응답 시간이다.
- **행 적중**: 이미 활성화된 행에서 열만 선택해 ACT•PRE 비용을 피하는 접근이다.
- **PHY 트레이닝**: Physical Layer Training, DQ와 DQS 지연을 보정해 샘플링 시점을 맞추는 절차이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 뱅크 리프레시와 요청이 겹쳐 **꼬리 지연 증가** | **뱅크별 리프레시** 또는 한산 구간 실행으로 차단 분산 | 지연 민감 요청의 **최대 대기 시간 완화** |
| 행 미적중이 반복되어 **ACT·PRE 명령 증가** | 행 지역성을 높이는 **주소 매핑·요청 재정렬** | 행 적중 증가로 **명령 비용 감소·처리량 향상** |
| 고온에서 전하 누설이 빨라져 **데이터 보존 시간 단축** | 온도 센서에 따라 **리프레시 주기 단축** | 전하 손실 전 복원으로 **데이터 보존 확보** |
| 전송률 상승으로 **DQ·DQS 샘플링 마진 감소** | 부팅·운용 중 **PHY 트레이닝과 오류 감시** | 데이터 샘플링 지점 보정으로 **신호 무결성 유지** |

#### 한줄 요약

- 뱅크별 리프레시는 갱신 중에도 다른 뱅크 접근을 허용해 전체 랭크 차단에 따른 꼬리 지연을 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **지연 민감 구간**: 리프레시로 인한 일시 중단이 서비스 응답 목표를 위반할 수 있는 처리 구간이다.
- **절전 대기**: 외부 접근이 없는 동안 컨트롤러와 클록을 멈추고 메모리만 데이터를 보존하는 상태이다.

</details>

- 지연 민감은 **뱅크별**, 절전 대기는 **자체 리프레시**를 선택한다.

#### 한줄 요약

- 지연 민감 요청이 계속되면 뱅크별 리프레시를, 외부 접근이 없는 절전 상태에서는 자체 리프레시를 선택한다.
