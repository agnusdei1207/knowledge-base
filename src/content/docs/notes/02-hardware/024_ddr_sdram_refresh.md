## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate Synchronous Dynamic RAM)**: 시스템 클록의 상승(Rising)과 하강(Falling) 양 엣지에서 데이터를 전송하여 동일 버스 주파수 대비 2배의 대역폭을 제공하는 동기식 DRAM.
- **전하 누설(Charge Leakage)**: DRAM 셀 커패시터의 유전체를 통해 전하가 서서히 방전되어 저장된 논리 데이터가 소실되는 물리적 현상.
- **리프레시(Refresh)**: 커패시터 전하가 소실되기 전에 전체 행을 주기적으로 판독·재충전하여 데이터를 보존하는 동작.

</details>

- 정의/개념: 클록의 상승·하강 엣지 모두에서 데이터를 전송하는 **DDR SDRAM** 기술 및 커패시터 전하 누설을 보구하는 **리프레시** 메커니즘 기반 고속 동기식 메모리
- 배경/필요성: 핀 수를 늘리기 어려워 전송 시점을 늘려야 했고, 동시에 **전하 누설** 기반 방치된 행은 데이터가 소실됨

#### 한줄 요약
- 대역폭을 늘리는 기술과 데이터를 지키는 의무가 같은 장치 안에서 부딪히므로, DDR 규격의 복잡성은 성능 욕심이 아니라 이 충돌의 조정 결과다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **양 엣지 전송(Double-Edge Transfer)**: 클록 신호의 상승 모서리와 하강 모서리에서 각각 1회씩 데이터를 래치하여 버스 클록의 2배 속도로 데이터를 전송하는 방식.
- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**: 메모리를 물리적으로 독립된 복수의 뱅크(Bank) 구조로 분할하여 한 뱅크의 지연 시간 동안 다른 뱅크의 읽기/쓰기를 중첩 처리하는 기법.
- **버스트 길이(Burst Length, BL)**: 단일 읽기/쓰기 명령으로 메모리 버스를 통해 연속적으로 송수신되는 데이터 단위 길이.

</details>

- **양 엣지 전송** 기반 동일 클록에서 핀당 전송률 두 배 향상
- **뱅크 수준 병렬성** 기반 다른 뱅크의 요청을 중첩 처리하여 유효 대역폭 향상
- **리프레시** 명령 실행 중 해당 뱅크 접근 차단으로 꼬리 지연 발생

#### 한줄 요약
- **뱅크 수준 병렬성** 대역폭을 끌어올리는 동시에 리프레시 차단 범위를 좁히는 수단이 되므로, 뱅크 분할은 성능과 지연 두 문제를 함께 다룬다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: CPU의 메모리 접근 요청을 해석하여 JEDEC 타이밍 규격에 맞춰 DRAM 명령을 스케줄링하고 전송하는 제어 장치.
- **DDR 물리 계층(DDR Physical Interface, PHY)**: 제어기의 논리 신호와 DRAM 모듈 간의 임피던스 매칭, 신호 정렬, DQS 스트로브 동기화를 담당하는 인터페이스.
- **행 버퍼(Row Buffer)**: 행 활성화(Active) 시 선택된 전체 행의 커패시터 데이터를 감지 증폭기가 일괄 래치하여 보관하는 고속 임시 데이터 버퍼.

</details>

```text
[메모리 제어기] ── [DDR PHY] ── [DRAM 배열]
       │                │              ├─ 뱅크·행 버퍼
 명령·리프레시      신호·타이밍         └─ 리프레시 제어
   스케줄링             정합              전하 복원
```

선의 의미: `──`는 명령·주소·데이터 연결, 가지는 DRAM 배열 내부의 저장·복원 책임

| 구성요소 | 책임 |
|:---|:---|
| **메모리 제어기** | 읽기·쓰기·리프레시 명령의 순서와 타이밍 결정 |
| **DDR PHY** | **양 엣지 전송** 신호와 샘플링 타이밍 정합 |
| 뱅크·**행 버퍼** | 활성 행을 래치해 연속 열 접근과 요청 중첩 제공 |
| 리프레시 제어 | 누설 전하 주기 복원으로 데이터 보존 |

#### 한줄 요약
- 성능을 실제로 좌우하는 것은 DRAM 소자가 아니라 명령 순서를 정하는 제어기이며, 같은 메모리도 스케줄링 정책에 따라 유효 대역폭이 크게 갈린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **리프레시 간격(Refresh Interval Time, tREFI)**: 모든 메모리 행이 보존 시간 내에 재충전되도록 제어기가 리프레시 명령을 발행해야 하는 평균 주기 기준.
- **리프레시 사이클 시간(Refresh Cycle Time, tRFC)**: 단일 리프레시 명령 수행 중 커패시터 재충전을 위해 해당 뱅크의 일반 접근이 완전히 차단되는 최소 소요 시간.
- **프리차지(Precharge)**: 다음 행 접근 전 뱅크 비트라인을 기준 전압으로 초기화하는 동작.

</details>

```text
메모리 제어기 타이머 확인
      │
      ├─ tREFI 도래 → [ 1. 리프레시 명령 발행 및 차단 ]
      │                    │
      │              리프레시 명령 발행 → tRFC 동안 차단 → 완료 후 재개
      │
      └─ [ 2. 일반 접근 행 활성화 및 열 전송 ]
             │
         행 활성화 → 읽기·쓰기 명령 → 버스트 길이만큼 전송 → 프리차지
```

분기 결과: **tREFI** 기반 미룰 수 있는 평균 기준이지만 **tRFC** 기반 시작하면 줄일 수 없으므로, 제어기가 조정할 수 있는 것은 시점뿐이고 비용 자체는 고정

#### 한줄 요약
- 리프레시는 총량을 줄일 수 없고 배치만 바꿀 수 있으므로, 최적화의 목표가 평균 성능이 아니라 꼬리 지연의 분산으로 옮겨 간다.

## Ⅴ. 종류 및 비교

| 리프레시 방식 | 전체 뱅크 리프레시 | 뱅크별 리프레시 | 자체 리프레시(Self-Refresh) |
|:---|:---|:---|:---|
| 적용 기준 | 단순 제어 우선·저빈도 접근 | 접근 차단 분산 필요 | 저전력 대기 상태(전원 절약) |
| 핵심 특징 | 전체 범위 한 번에 복원 | 일부 뱅크 중심 복원·중첩 가능 | DRAM 내부 타이머 기반 자율 복원 |
| 한계 | 차단 범위가 넓고 tRFC가 길어 꼬리 지연 발생 | 스케줄링 복잡도 증가 | 대기 상태에서 일반 접근 불가 |

#### 한줄 요약
- 세 방식은 같은 전하 복원량을 시간과 공간에 어떻게 흩뿌릴지의 선택이며, 총 비용이 아니라 그 비용이 언제 누구에게 부과되는지만 달라진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표적 행 리프레시(Targeted Row Refresh, TRR)**: 특정 행의 과도한 반복 활성화(Row Hammer) 감지 시 취약한 인접 행들을 선제적으로 추가 복원하는 하드웨어 보호 기법.
- **메모리 트레이닝(Memory Training)**: 부팅 시 신호 전송선 지연과 왜곡을 보정하여 최적의 데이터 샘플링 위상을 맞추는 초기화 절차.
- **오류 정정 코드(Error Correcting Code, ECC)**: 패리티 비트를 통해 데이터 전송 및 저장 시 발생하는 비트 플립 오류를 검출하고 정정하는 메커니즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 리프레시의 긴 **tRFC** 꼬리 지연 | 뱅크별 리프레시·요청 스케줄 조정 | 접근 차단 범위 분산 |
| 특정 행 반복 접근으로 인접 행 오류 | **TRR**·**ECC** 적용 및 범위 검증 | Row Hammer 완화·오류 정정 |
| 고온에서 **전하 누설** 가속 | 온도 기반 tREFI 단축 적용 | 데이터 보존 여유 확보 |
| 고속 양 엣지 신호의 타이밍 오류 | **메모리 트레이닝**·신호 무결성 검증 | 샘플링 오류 감소 |

#### 한줄 요약
- 온도가 리프레시 주기를 결정한다는 사실 때문에 냉각 설계가 곧 메모리 성능 설계가 되며, 열이 오르면 대역폭이 조용히 깎인다.

## Ⅶ. 결론

- 지연 민감 시스템은 지원 범위에서 뱅크별 리프레시로 차단을 분산하고, 저전력 대기는 자체 리프레시를 쓰되 온도별 리프레시 주기와 최악 지연을 함께 검증

#### 한줄 요약
- DDR 규격에서 평균 대역폭은 데이터시트가 보장하지만 최악 지연은 보장하지 않으므로, 실시간 시스템이 실제로 검증해야 하는 값은 후자다.
