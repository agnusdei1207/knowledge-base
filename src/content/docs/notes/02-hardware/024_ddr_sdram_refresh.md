## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate Synchronous Dynamic RAM)**: 시스템 버스 클록의 상승(Rising)과 하강(Falling) 양 엣지에서 데이터를 모두 전송하여 동일 주파수 대비 대역폭을 2배로 확장한 동기식 DRAM.
- **전하 누설(Charge Leakage)**: DRAM 단위 셀 커패시터의 유전체를 통해 전하가 서서히 방전되어 저장된 비트 데이터가 소실되는 물리적 현상.
- **리프레시(Refresh)**: 전하가 임계치 이하로 소실되기 전에 전체 행(Row)을 주기적으로 감지 증폭기로 읽어 재충전하는 데이터 보존 동작.

</details>

- 정의/개념: **양 엣지 전송**과 **리프레시**를 결합한 동기식 DRAM
- 배경/필요성: 단일 클록 에지 전송(SDR)의 대역폭 한계와 DRAM 커패시터의 자연 전하 누설로 인한 **데이터 휘발성 소실 위험**

#### 한줄 요약
- DDR SDRAM은 클록 양 엣지 전송으로 대역폭을 2배 높이고, 주기적 리프레시를 통해 휘발성 셀의 데이터 무결성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **양 엣지 전송(Double-Edge Transfer)**: 클록 상승 및 하강 엣지마다 1회씩 데이터를 래치하여 버스 클록 주파수의 2배 데이터 레이트(MT/s)를 달성하는 기술.
- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**: 메모리 내부를 다수의 독립 뱅크(Bank)로 분할하여 한 뱅크의 지연 시간 동안 다른 뱅크의 요청을 중첩 처리하는 기법.
- **버스트 길이(Burst Length, BL)**: 1번의 읽기/쓰기 명령으로 연속 입출력되는 데이터 비트의 길이(DDR4: BL8, DDR5: BL16).

</details>

- **양 엣지 전송**과 프리페치로 핀당 전송률 향상
- **BLP** 기반 비리프레시 뱅크의 요청 중첩 처리
- **리프레시** 중 $t_{RFC}$ 동안 접근 차단 지연 발생

#### 한줄 요약
- 양 엣지 전송과 뱅크 병렬성으로 대역폭을 극대화하며, 리프레시 차단 지연을 분산시키는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: CPU 요청을 해석하여 JEDEC 타이밍 규격($t_{RCD}, t_{RP}, t_{RFC}$)에 맞추어 명령어를 스케줄링하는 하드웨어 유닛.
- **DDR PHY(Physical Layer)**: 제어기의 논리 신호와 DRAM 칩 간의 신호 왜곡 보정, DQS 데이터 스트로브 정렬, 전압 레벨을 변환하는 물리 인터페이스.
- **행 버퍼(Row Buffer)**: 행 활성화(ACT) 시 감지 증폭기가 한 행 전체의 데이터를 래치하여 고속 열 접근을 지원하는 버퍼.

</details>

```text
DDR SDRAM 서브시스템 아키텍처
├── 메모리 제어기 (IMC): Out-of-Order 명령 스케줄러 및 tREFI 리프레시 타이머
├── DDR PHY 인터페이스: 양 엣지 전송 신호 정합 및 DQS 데이터 스트로브 동기화
├── DRAM 뱅크 어레이: 1T1C 셀 매트릭스 및 감지 증폭기 행 버퍼 (BLP 지원)
└── 온칩 리프레시 제어기: 커패시터 전하 주기적 재충전 회로 (tRFC 제어)
```

선의 의미: 가지(`├──`, `└──`)는 프로세서 내 메모리 제어기부터 DRAM 칩 내부 회로까지의 하드웨어 구성요소 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 메모리 제어기 | 읽기·쓰기와 **리프레시 스케줄링** 제어 |
| DDR PHY | **양 엣지 전송** 신호 정합과 DQS 동기화 |
| DRAM 뱅크·행 버퍼 | 행 래치와 **버스트 접근** 제공 |
| 온칩 리프레시 회로 | $t_{RFC}$ 동안 셀 **전하 재충전** |

#### 한줄 요약
- DDR 시스템은 메모리 제어기(명령/타이밍), PHY(신호 정합), DRAM 뱅크 및 온칩 리프레시 회로가 유기적으로 연동된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **tREFI(Refresh Interval Time)**: 메모리 제어기가 리프레시 명령을 발행해야 하는 평균 주기(표준 $7.8\mu s$, 고온 시 $3.9\mu s$).
- **tRFC(Refresh Cycle Time)**: 단일 리프레시 명령 수행 시 커패시터 재충전 완료까지 해당 메모리가 차단되는 시간(수백 ns).

</details>

```text
메모리 제어기 타이머의 tREFI 주기 도래
                      │
                      ▼
1. 리프레시 방식에 따른 제어 흐름 판정
   ┌──────────────────┴──────────────────┐
[ 전체 뱅크 리프레시 (All-Bank REF) ]   [ 뱅크별 리프레시 (Per-Bank REF) ]
   │                                     │
   ▼                                     ▼
2. 모든 뱅크로 REF 명령 브로드캐스트    3. 특정 단일 뱅크로만 PB-REF 명령 발행
   │                                     │
   ▼                                     ▼
4. 전체 메모리 접근 차단 ($t_{RFC}$)    5. 해당 뱅크만 $t_{RFCpb}$ 동안 차단
   (긴 꼬리 지연 발생)                   (타 뱅크는 정상 읽기/쓰기 동시 수행)
   │                                     │
   └──────────────────┬──────────────────┘
                      │
                      ▼
커패시터 전하 복원 완료 후 일반 읽기/쓰기 스케줄링 재개
```

분기 결과: **전체 뱅크 리프레시**는 모든 접근이 중단되어 꼬리 지연이 크나, **뱅크별 리프레시**는 타 뱅크 접근을 허용하여 시스템 응답성을 유지함

**동작 원리**

1. **리프레시 방식에 따른 제어 흐름 판정**: 지연 목표로 방식 선택
2. **모든 뱅크로 REF 명령 브로드캐스트**: 전체 행 재충전 요청
3. **특정 단일 뱅크로만 PB-REF 명령 발행**: 대상 뱅크만 요청
4. **전체 메모리 접근 차단**: $t_{RFC}$ 동안 모든 요청 대기
5. **해당 뱅크만 차단**: 타 뱅크의 읽기·쓰기 허용

#### 한줄 요약
- 리프레시 주기가 도래하면 제어기가 REF 명령을 발행하며, 뱅크별 리프레시를 통해 타 뱅크 접근 중단을 방지한다.

## Ⅴ. 종류 및 비교

| 리프레시 방식 | 전체 뱅크 | 뱅크별 | 자체 리프레시 |
|:---|:---|:---|:---|
| 적용 기준 | 단순한 정상 동작 | 낮은 **꼬리 지연** | 저전력 대기 상태 |
| 핵심 특징 | 전체 뱅크 **동시 리프레시** | 뱅크별 **순차 리프레시** | 내부 타이머의 **자율 리프레시** |
| 한계 | $t_{RFC}$ 동안 전체 접근 차단 | 제어·스케줄링 복잡도 증가 | 외부 접근 불가와 복귀 지연 |

#### 한줄 요약
- 단순 제어에는 전체 뱅크 리프레시가 쓰였으나, DDR5 및 LPDDR5에서는 꼬리 지연을 없애기 위해 뱅크별 리프레시가 표준이 되었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표적 행 리프레시(Targeted Row Refresh, TRR)**: 특정 행의 반복 활성화(Row Hammer 공격) 감지 시 취약한 인접 행들을 선제적으로 추가 재충전하는 기법.
- **DDR5 On-Die ECC**: 셀 미세화에 따른 신뢰성 저하를 방어하기 위해 DRAM 다이 내부에 자체 에러 정정 회로를 탑재한 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 리프레시로 인한 실시간 작업의 극심한 꼬리 지연 | **뱅크별 리프레시**(Per-Bank REF) 및 분산 스케줄링 | 접근 차단 구간 분산 및 최악 지연 60% 이상 단축 |
| 악의적 반복 접근으로 인접 셀 전하를 유출시키는 Row Hammer | **TRR**(Targeted Row Refresh) 및 **On-Die ECC** 적용 | 비트 플립 오류 방지 및 메모리 신뢰성 확보 |
| 고온 환경($>85^\circ\text{C}$)에서 전하 누설 가속화 | **가변 리프레시**(Auto-Temperature REF) 적용 | 데이터 보존 시간 확보 및 데이터 유실 원천 차단 |

#### 한줄 요약
- 실무에서는 뱅크별 리프레시로 꼬리 지연을 방어하고, TRR 및 On-Die ECC로 Row Hammer와 비트 플립을 통제한다.

## Ⅶ. 결론

- DDR5/LPDDR5 표준에서 **뱅크별 리프레시(Per-Bank Refresh), On-Die ECC, 듀얼 서브채널 구조**로 발전하여 대역폭과 신뢰성을 확보하였으며, 향후 고성능 AI 및 서버 환경에서는 **DDR5-MRDIMM 및 CXL 메모리 모듈** 형태로 대역폭·용량 확장 진화 추세

#### 한줄 요약
- DDR SDRAM은 양 엣지 전송으로 대역폭을 극대화하며, 뱅크별 리프레시와 온다이 ECC를 통해 성능과 신뢰성을 완성한다.
