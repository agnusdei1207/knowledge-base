## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate Synchronous DRAM)**: 클록의 상승·하강 양 엣지에서 데이터를 전송해 동일 클록 주파수 대비 두 배 대역폭을 제공하는 동기식 DRAM.
- **전하 누설(Charge Leakage)**: DRAM 커패시터의 저장 전하가 시간에 따라 감소하는 현상; 방치 시 데이터 손실.
- **리프레시(Refresh)**: 누설되기 전 행의 전하를 재충전해 데이터를 보존하는 필수 동작; 접근 차단 원인.

</details>

- 정의/개념: 클록의 두 엣지에서 데이터를 보내는 **DDR SDRAM(Double Data Rate Synchronous DRAM)**과, 커패시터 전하를 되살리는 **리프레시**가 함께 동작하는 고속 동기식 메모리
- 배경/필요성: 핀 수를 늘리기 어려워 전송 시점을 늘려야 했고, 동시에 **전하 누설**로 방치된 행은 데이터가 소실됨

#### 한줄 요약
- 대역폭을 늘리는 기술과 데이터를 지키는 의무가 같은 장치 안에서 부딪히므로, DDR 규격의 복잡성은 성능 욕심이 아니라 이 충돌의 조정 결과다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**: 여러 독립 메모리 뱅크를 동시 활용해 요청을 겹쳐 처리하는 구조.
- **버스트 길이(Burst Length)**: 하나의 명령으로 연속 전송하는 데이터 단위 수; 내부 버스 효율 결정.
- **양 엣지 전송(Double-Edge Transfer)**: 클록의 상승·하강 두 전이 시점에서 데이터를 전달해 핀당 전송률을 두 배로 높이는 방식.

</details>

- **양 엣지 전송**으로 동일 클록에서 핀당 전송률 두 배 향상
- **뱅크 수준 병렬성**으로 다른 뱅크의 요청을 중첩 처리하여 유효 대역폭 향상
- **리프레시** 명령 실행 중 해당 뱅크 접근 차단으로 꼬리 지연 발생

#### 한줄 요약
- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**이 대역폭을 끌어올리는 동시에 리프레시 차단 범위를 좁히는 수단이 되므로, 뱅크 분할은 성능과 지연 두 문제를 함께 다룬다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: DRAM 명령·주소·타이밍과 리프레시를 스케줄링하는 제어기.
- **DDR PHY(DDR Physical Interface)**: 메모리 제어기와 DRAM 사이의 고속 전기 신호를 송수신하고 타이밍을 맞추는 인터페이스.
- **행 버퍼(Row Buffer)**: 활성화된 DRAM 행의 데이터를 래치해 연속 열 접근을 가속하는 버퍼.

</details>

```text
[메모리 제어기] ── [DDR PHY] ── [DRAM 배열]
       │                │              ├─ 뱅크·행 버퍼
 명령·리프레시      신호·타이밍         └─ 리프레시 제어
   스케줄링             정합              전하 복원
```

선의 의미: `──`는 명령·주소·데이터 연결, 가지는 DRAM 배열 내부의 저장·복원 책임

| 구성요소 | 책임 |
|:---|:---|
| **메모리 제어기** | 읽기·쓰기·리프레시 명령의 순서와 타이밍 결정 |
| **DDR PHY** | **양 엣지 전송** 신호와 샘플링 타이밍 정합 |
| 뱅크·**행 버퍼** | 활성 행을 래치해 연속 열 접근과 요청 중첩 제공 |
| 리프레시 제어 | 누설 전하 주기 복원으로 데이터 보존 |

#### 한줄 요약
- 성능을 실제로 좌우하는 것은 DRAM 소자가 아니라 명령 순서를 정하는 제어기이며, 같은 메모리도 스케줄링 정책에 따라 유효 대역폭이 크게 갈린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **리프레시 간격(tREFI)**: 정해진 시간 창에서 리프레시 명령을 배치하기 위한 평균 간격 기준.
- **리프레시 사이클 시간(tRFC)**: 리프레시 명령 실행 동안 해당 뱅크의 일반 접근이 차단되는 시간.
- **프리차지(Precharge)**: 다음 행 접근 전 뱅크 비트라인을 기준 전압으로 초기화하는 동작.

</details>

```text
메모리 제어기 타이머 확인
      │
      ├─ tREFI 도래 → [ 1. 리프레시 명령 발행 및 차단 ]
      │                    │
      │              리프레시 명령 발행 → tRFC 동안 차단 → 완료 후 재개
      │
      └─ [ 2. 일반 접근 행 활성화 및 열 전송 ]
             │
         행 활성화 → 읽기·쓰기 명령 → 버스트 길이만큼 전송 → 프리차지
```

분기 결과: **리프레시 간격(tREFI)**은 미룰 수 있는 평균 기준이지만 **리프레시 사이클 시간(tRFC)**은 시작하면 줄일 수 없으므로, 제어기가 조정할 수 있는 것은 시점뿐이고 비용 자체는 고정

#### 한줄 요약
- 리프레시는 총량을 줄일 수 없고 배치만 바꿀 수 있으므로, 최적화의 목표가 평균 성능이 아니라 꼬리 지연의 분산으로 옮겨 간다.

## Ⅴ. 종류 및 비교

| 리프레시 방식 | 전체 뱅크 리프레시 | 뱅크별 리프레시 | 자체 리프레시(Self-Refresh) |
|:---|:---|:---|:---|
| 적용 기준 | 단순 제어 우선·저빈도 접근 | 접근 차단 분산 필요 | 저전력 대기 상태(전원 절약) |
| 핵심 특징 | 전체 범위 한 번에 복원 | 일부 뱅크 중심 복원·중첩 가능 | DRAM 내부 타이머 기반 자율 복원 |
| 한계 | 차단 범위가 넓고 tRFC가 길어 꼬리 지연 발생 | 스케줄링 복잡도 증가 | 대기 상태에서 일반 접근 불가 |

#### 한줄 요약
- 세 방식은 같은 전하 복원량을 시간과 공간에 어떻게 흩뿌릴지의 선택이며, 총 비용이 아니라 그 비용이 언제 누구에게 부과되는지만 달라진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표적 행 리프레시(Target Row Refresh, TRR)**: 특정 행의 반복 활성화로 인접 행 오류 우려 시 주변 행을 추가 복원하는 완화 기법.
- **메모리 트레이닝(Memory Training)**: 부팅 시 데이터 신호와 샘플링 타이밍을 맞추는 초기화 절차.
- **오류 정정 코드(Error Correcting Code, ECC)**: 저장 데이터의 오류를 검출하고 일부를 정정하는 코드.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 리프레시의 긴 **tRFC** 꼬리 지연 | 뱅크별 리프레시·요청 스케줄 조정 | 접근 차단 범위 분산 |
| 특정 행 반복 접근으로 인접 행 오류 | **TRR**·**ECC** 적용 및 범위 검증 | Row Hammer 완화·오류 정정 |
| 고온에서 **전하 누설** 가속 | 온도 기반 tREFI 단축 적용 | 데이터 보존 여유 확보 |
| 고속 양 엣지 신호의 타이밍 오류 | **메모리 트레이닝**·신호 무결성 검증 | 샘플링 오류 감소 |

#### 한줄 요약
- 온도가 리프레시 주기를 결정한다는 사실 때문에 냉각 설계가 곧 메모리 성능 설계가 되며, 열이 오르면 대역폭이 조용히 깎인다.

## Ⅶ. 결론

- 지연 민감 시스템은 지원 범위에서 뱅크별 리프레시로 차단을 분산하고, 저전력 대기는 자체 리프레시를 쓰되 온도별 리프레시 주기와 최악 지연을 함께 검증

#### 한줄 요약
- DDR 규격에서 평균 대역폭은 데이터시트가 보장하지만 최악 지연은 보장하지 않으므로, 실시간 시스템이 실제로 검증해야 하는 값은 후자다.
