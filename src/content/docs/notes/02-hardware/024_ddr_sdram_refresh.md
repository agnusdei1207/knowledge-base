## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate SDRAM)**: 클록 신호의 상승(Rising)과 하강(Falling) 엣지 양쪽에서 데이터를 전송하여 대역폭을 2배 높인 동기식 DRAM.
- **전하 누설(Charge Leakage)**: 1T1C 커패시터에 저장된 전하가 시간 경과에 따라 기생 저항을 통해 자연 방전되는 물리 현상.
- **리프레시(Refresh)**: 커패시터 전하가 소멸하기 전 주기적으로 행(Row)을 읽어 전압을 다시 충전해주는 동작.

</details>

- 정의/개념: 클록의 상승/하강 양 엣지(Double Edge)에서 데이터를 전송하고, 뱅크 병렬성과 커패시터 전하 누설 방지용 리프레시(Refresh) 메커니즘을 결합한 동기식 DRAM 규격
- 배경/필요성: 단일 엣지 전송의 대역폭 한계를 극복하고, 초미세 공정화에 따른 **커패시터 전하 누설(Data Retention Failure) 및 Row Hammer 보안 취약점 극복**

#### 한줄 요약

- 클록 양 엣지 전송(DDR)과 **주기적 리프레시(tREFI/tRFC)**를 결합한 고속 메인 메모리

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **뱅크 병렬성(Bank-Level Parallelism, BLP)**: 메모리 내부를 독립적인 다수의 뱅크로 나누어 인터리빙 방식으로 동시 접근을 가능케 하는 구조.
- **버스트 길이(Burst Length)**: 단일 읽기/쓰기 명령으로 연속 인출되는 데이터 블록의 단위 수량(DDR4: BL8, DDR5: BL16).

</details>

- 클록의 **양 엣지 전송(Double-Edge)** 기술 적용을 통한 동일 클록 주파수 대비 2배 전송 속도 달성
- 다중 뱅크 그룹 구조의 **뱅크 병렬성(BLP)**과 **버스트 전송**을 통한 메모리 접근 지연 은닉 및 대역폭 확장
- JEDEC 표준에 따른 **tREFI(리프레시 간격)** 및 **tRFC(리프레시 사이클 시간)** 타이밍 규격 준수 필수

#### 한줄 요약

- **양 엣지 전송과 뱅크 병렬성**으로 대역폭을 극대화하며 리프레시 오버헤드 수반

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 컨트롤러(IMC)**: CPU 내부에서 메모리 타이밍(tCAS, tRCD, tRP, tRFC)을 준수하며 명령을 스케줄링하는 유닛.
- **DDR PHY**: 컨트롤러의 디지털 신호를 고속 차동 아날로그 전기 신호로 변환하는 물리 계층 인터페이스.

</details>

```text
[ 메모리 인터페이스 및 컨트롤러 아키텍처 ]
+---------------------------------------------------+
| 메모리 컨트롤러 (주소 매핑, 명령어 스케줄러)      |
|  └─ 리프레시 타이머 (tREFI) 및 우선순위 큐        |
+---------------------------------------------------+
                          │
+---------------------------------------------------+
| 물리 계층 (DDR PHY: DQS 스트로브 및 신호 보정)    |
+---------------------------------------------------+
                          │
+---------------------------------------------------+
| DRAM 칩 배열 (다중 뱅크 그룹)                      |
|  ├─ Bank Group 0 ~ N (Row Buffer 및 Sense Amp)     |
|  └─ 온칩 리프레시 카운터 및 TRR 보호 로직         |
+---------------------------------------------------+
```

선의 의미: 메모리 컨트롤러, 고속 PHY 계층, 뱅크 그룹(행 버퍼) 및 내장 리프레시 카운터 간의 DDR 인터페이스 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 메모리 컨트롤러 | 주소 파싱 및 메모리 접근 명령과 리프레시 스케줄링 총괄 |
| 물리 계층 (DDR PHY) | 초고속 아날로그 전기 신호 변환 및 통신 데이터 무결성 제어 |
| 행 버퍼 (Row Buffer) | 활성화된 행 전체의 전하 감지 및 복원, 고속 열 접근 지원 |
| 리프레시 카운터 | 타이머 주기에 맞춰 다음 리프레시가 수행될 대상 행 선택 |

#### 한줄 요약

- **메모리 컨트롤러·DDR PHY·뱅크 그룹(행 버퍼)·리프레시 카운터** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **tREFI (7.8$\mu$s / 3.9$\mu$s)**: 리프레시 명령이 발행되어야 하는 평균 주기.
- **tRFC (Refresh Cycle Time)**: 리프레시 명령이 실행되는 동안 해당 뱅크가 락업되어 외부 명령을 받지 못하는 시간.

</details>

```text
[ 메모리 컨트롤러 스케줄러 루프 ]
                 │
                 ▼
     [ 1. tREFI 타이머 만료 여부 검사 ]
                 │
       ┌─────────┴─────────┐
       ▼ [만료 시]         ▼ [정상 상태]
 [ 2. 리프레시 명령 발행 ] [ 3. 일반 읽기/쓰기 스케줄링 ]
       │                   │
       ▼                   ▼
 [ tRFC 동안 뱅크 락업 ]   [ Row Active (tRCD) ──> Col Read (tCAS) ]
       │                   │
       ▼                   ▼
 [ 전하 재충전 완료 ]      [ Precharge (tRP) 로 Row 닫기 ]
```

**동작 원리**

1. **타이머 검사**: 메모리 컨트롤러가 내부 타이머를 모니터링하여 tREFI 주기가 도래했는지 확인
2. **리프레시 실행**: 리프레시 명령을 DRAM으로 전송하고, DRAM 내부 카운터가 지정 행을 읽어 재충전(tRFC 소요)
3. **일반 접근**: 리프레시가 없을 때는 Row Active(행 열기) $\to$ Column Read/Write(데이터 전송) $\to$ Precharge(행 닫기) 파이프라인 수행

#### 한줄 요약

- tREFI 타이머 도래 시 **리프레시 락업(tRFC)을 우선 수행하고 평상시에는 Row Active-Precharge 반복**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **All-Bank vs Per-Bank vs Self-Refresh**:
  - All-Bank: 전체 뱅크를 동시에 리프레시 (DDR3/4)
  - Per-Bank (PBBR): 1개 뱅크만 리프레시하고 타 뱅크는 정상 가동 (LPDDR4/5, DDR5)
  - Self-Refresh: 외부 클록 없이 칩 자체 타이머로 절전 모드 유지

</details>

| 비교 항목 | 전체 뱅크 리프레시 (All-Bank) | 뱅크별 리프레시 (Per-Bank, PBBR) | 자체 리프레시 (Self-Refresh) |
|:---|:---|:---|:---|
| 적용 기준 | DDR3, DDR4 등 레거시 메모리 표준 환경 | LPDDR4/5, DDR5 등 초고속/저지연 요구 환경 | 모바일 단말, 랩톱 배터리 절전 및 시스템 대기 모드 |
| 핵심 특징 | 단일 명령으로 랭크 내 모든 뱅크를 일제히 락업하고 동시 충전 | 특정 1개 뱅크만 락업하고 타 뱅크는 정상적인 읽기/쓰기 병행 | 외부 클록 차단 후 온칩 자체 타이머로 자율 충전 유지 |
| 한계 | tRFC 동안 전체 메모리 접근이 중단되어 심각한 꼬리 지연 발생 | 제어 로직이 복잡해지고 뱅크별 스케줄링 오버헤드 추가 | 정상적인 데이터 접근이 불가하며 시스템 절전 시에만 유효 |

#### 한줄 요약

- All-Bank의 꼬리 지연을 극복하기 위해 **LPDDR/DDR5의 Per-Bank Refresh 표준 채택**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Target Row Refresh(TRR)**: 특정 행이 임계치 이상 활성화(Row Hammer)될 때, 인접 희생 행을 하드웨어적으로 즉시 추가 리프레시하여 비트 반전을 방어하는 기법.
- **Auto Self-Refresh(ASR)**: DRAM 내부 온도 센서에 따라 고온 시 리프레시 주기를 2배로 단축(85℃ 초과)하는 온도 감응 제어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 뱅크 리프레시 락업으로 인한 심각한 실시간 **꼬리 지연** 증대 | **뱅크별 리프레시** 체계 도입 및 지능형 뱅크 분산 스케줄링 | 접근 차단 시간 분산 및 지연 시간 대폭 삭감 |
| 특정 행의 비정상적 집중 접근 시 비트가 반전되는 **로해머** 공격 취약점 | 제어기 및 메모리 내부 **표적 행 리프레시** 회로 내장 연동 | 인접 행 강제 충전을 통한 비트 반전 공격 원천 차단 |
| 고온 환경 작동 시 전하 누설 가속으로 인한 치명적인 데이터 파손 한계 | 온도 센서 피드백 연동을 통한 리프레시 충전 간격 단축 제어 | 가혹한 고온 환경에서도 메모리 데이터 보존성 완벽 유지 |
| 초고속 양 엣지 전송 시 신호 타이밍 왜곡으로 인한 데이터 비트 오류 | 시스템 부팅 시 컨트롤러의 읽기/쓰기 훈련 및 동기 신호 조율 | 전기적 데이터 샘플링 여유 확보 및 신호 무결성 보장 |

#### 한줄 요약

- **Per-Bank Refresh·TRR(Row Hammer 방어)·온도 가변 리프레시(ASR)**로 신뢰성 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DDR5 아키텍처 진화**: 단일 64비트 채널을 듀얼 32비트 독립 서브채널로 분할하고, On-die ECC와 Per-Bank 리프레시를 표준 내장하여 대역폭과 신뢰성을 동시 달성.

</details>

- 미세 공정 DRAM의 한계를 극복하기 위해 **Per-Bank 리프레시, Target Row Refresh(TRR) 및 On-die ECC 필수 탑재**

#### 한줄 요약

- **대역폭 확장과 리프레시/Rowhammer 방어**를 통합한 차세대 DDR5/LPDDR5 메모리 구현
