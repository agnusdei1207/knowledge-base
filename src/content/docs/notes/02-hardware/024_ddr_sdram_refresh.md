## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM (Double Data Rate Synchronous DRAM)**: 시스템 버스 클록의 상승 엣지와 하강 엣지 모두에서 데이터를 전송하여 데이터 전송율을 2배 높인 동기식 동적 램 규격이다.
- **전하 누설 (Charge Leakage)**: 트랜지스터와 커패시터를 통해 동적 램의 전하가 서서히 방전되어 데이터가 변질되는 물리적 현상이다.
- **리프레시 (Refresh)**: 커패시터 전하가 완전 소멸하기 전에 감지 증폭기로 행을 읽어 전압을 다시 강제 재충전해주는 행위이다.

</details>

- 정의: 클록 양 엣지 전송과 뱅크 병렬성을 결합하고, **전하 누설** 차단을 위해 타이밍 규격 기반의 **리프레시**를 구동하는 메인 메모리 기술
- 배경: 단일 엣지 전송의 대역폭 한계를 극복하고, 초미세 공정화에 따른 전하 누설 문제를 하드웨어 리프레시 통제로 완벽히 수습하기 위함

#### 한줄 요약

- 양 엣지 데이터 전송과 병렬 접근을 지원하며, 전하 누설 방지를 위한 엄격한 리프레시 타이밍 규격을 결합한 메모리 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **양 엣지 전송(Double-Edge Transfer)**: 1개의 클록 주기 내에서 상승 및 하강 엣지 모두에 데이터를 싣는 버스 동기화 기술이다.
- **뱅크 병렬성(Bank-Level Parallelism)**: 단일 칩 내부를 독립적인 다수의 뱅크로 파티셔닝하여 다중 접근 명령을 동시 구동하는 아키텍처이다.
- **버스트 전송(Burst Transfer)**: 단 1회의 열 접근 명령으로 지정된 길이만큼 연속된 메모리 묶음 데이터를 연속 인출하는 기법이다.

</details>

- 클록의 **양 엣지 전송** 기술을 적용하여 단일 엣지 대비 동일 클록 주파수에서 2배의 전송 속도를 달성함.
- 다중 뱅크의 **뱅크 병렬성**과 **버스트 전송**을 통해 명령어 지연을 중첩시키고 대역폭을 비약적으로 향상함.
- 일정한 시간 내에 모든 행을 재충전해야 하는 물리적 대기 시간이 수반되어 필수적인 리프레시 오버헤드가 발생함.

#### 한줄 요약

- 고속 데이터 인출을 위한 엣지 전송과 병렬성을 지원하는 동시에 데이터 유지를 위한 주기적 재충전의 부담을 함께 수반한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 컨트롤러(Memory Controller)**: 중앙처리장치 내에 배치되어 주소를 파싱하고 접근 및 리프레시 명령 타이밍을 스케줄링하는 유닛이다.
- **물리 계층(DDR PHY)**: 컨트롤러의 논리 명령을 수십 기가헤르츠(GHz)의 고주파 아날로그 전기 신호로 정밀 변환하는 블록이다.
- **행 버퍼(Row Buffer)**: 뱅크 내부에서 선택된 행 전체의 전하를 읽어온 후 임시 보관하는 정적 램 성격의 고속 버퍼이다.
- **리프레시 카운터(Refresh Counter)**: 매 주기마다 재충전을 실행할 대상 칩 내부의 행 주소를 순차적으로 가산하는 내장 카운터이다.

</details>

```text
[ 메모리 인터페이스 및 컨트롤러 아키텍처 ]
+---------------------------------------------------+
| 메모리 컨트롤러 (주소 매핑, 명령어 스케줄러)      |
|  └─ 리프레시 타이머 및 명령 대기열                |
+---------------------------------------------------+
                          │
+---------------------------------------------------+
| 물리 계층 (아날로그 신호 변환 및 신호 무결성)     |
+---------------------------------------------------+
                          │
+---------------------------------------------------+
| 메모리 칩 배열 (다중 뱅크 그룹)                   |
|  ├─ 뱅크 0 ~ N (행 버퍼 및 감지 증폭기)           |
|  └─ 내장 리프레시 카운터                          |
+---------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **메모리 컨트롤러** | 주소 파싱 및 메모리 접근 명령과 리프레시 스케줄링 총괄 |
| **물리 계층** | 초고속 아날로그 전기 신호 변환 및 통신 데이터 무결성 제어 |
| 행 버퍼 | 활성화된 행 전체의 전하 감지 및 복원, 고속 열 접근 지원 |
| **리프레시 카운터** | 타이머 주기에 맞춰 다음 리프레시가 수행될 대상 행 선택 |

#### 한줄 요약

- 메모리 컨트롤러의 명령 통제 하에 물리 계층을 거쳐 칩 내부의 다중 뱅크와 리프레시 카운터가 유기적으로 연동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **행 활성(Activate)**: 해당 뱅크의 특정 행을 열어 감지 증폭기 기반의 행 버퍼로 데이터를 로드시키는 명령이다.
- **프리차지(Precharge)**: 개방된 행을 닫고 비트라인 전압을 기준 레벨로 초기화하여 다음 활성을 준비하는 명령이다.
- **리프레시 간격(Refresh Interval)**: 전체 행을 나누어 전하 충전하기 위해 컨트롤러가 발송하는 평균 리프레시 명령의 시간 간격이다.
- **리프레시 주기 시간(Refresh Cycle Time)**: 리프레시 명령 수신 시 칩 내부가 완료할 때까지 타 명령을 거부하고 전면 대기하는 시간이다.

</details>

```text
[ 메모리 컨트롤러 명령어 수행 루프 ]
                 │
                 ▼
     [ 1. 리프레시 기한 도래 여부 검사 ]
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
 [ 기한 도래 ]         [ 일반 정상 접근 ]
       │                   │
       ▼                   ▼
 [ 2. 리프레시 수행 ]  [ 3. 일반 접근 제어 ]
       │                   │ (행 활성 및 열 전송)
       ▼                   ▼
 [ 대기 시간 락업 ]    [ 4. 프리차지 초기화 ]
```

### 동작 원리

1. 기한 확인: 설정된 **리프레시 간격** 타이머를 감시하여 기한 도래 여부를 지속 확인함.
2. 리프레시 수행: 기한 도래 시 대상 행을 복원하고 **리프레시 주기 시간** 동안 일반 접근을 통제 락업함.
3. 일반 접근: 타이머 만료 전의 정상 상태면 **행 활성** 및 데이터 버스트 전송을 즉각 수행함.
4. 프리차지: 데이터 전송 완료 후 **프리차지** 명령으로 비트라인을 초기화하여 다음 접근을 대기함.

#### 한줄 요약

- 리프레시 기한이 도래하면 메모리 접근을 전면 중단하고 충전을 우선 수행하며, 평상시에는 행 활성 기반 전송 사이클을 반복한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전체 뱅크 리프레시(All-Bank Refresh)**: 단일 명령으로 랭크 내의 모든 뱅크를 일제히 락업시키고 리프레시를 동시 수행하는 고전적 방식이다.
- **뱅크별 리프레시(Per-Bank Refresh)**: 특정 1개 뱅크만 락업하여 재충전하고, 타 뱅크는 정상적인 연산을 병렬로 허용하는 지연 은닉 방식이다.
- **자체 리프레시(Self Refresh)**: 시스템 절전 모드 진입 시 외부 컨트롤러 클록을 끄고 메모리 칩 온칩 타이머로 충전을 자율 수행하는 상태이다.

</details>

| 비교 항목 | 전체 뱅크 리프레시 | 뱅크별 리프레시 | 자체 리프레시 |
|:---|:---|:---|:---|
| 작동 메커니즘 | 랭크 내 모든 뱅크 일제히 락업 리프레시 | 특정 뱅크만 락업하고 타 뱅크는 정상 가동 | 외부 클록 차단 후 온칩 타이머 자율 충전 |
| 버스 대기 영향 | 충전 시간 동안 랭크 전면 접근 불가로 꼬리 지연 심화 | 타 뱅크 정상 접근 가능으로 지연시간 극소화 | 시스템 대기 모드 시 버스 접근 전면 차단 |
| 적용 표준 | 초기 및 이전 세대의 메모리 규격 표준 | 고성능 및 저전력 모바일 최신 메모리 규격 | 모바일 기기 및 노트북 절전 대기(S3) 모드 |
| 제어 복잡도 | 칩 내부 및 컨트롤러 제어 논리 로직이 단순함 | 컨트롤러의 명령 인터리빙 스케줄러 구현 복잡 | 칩 내부 자체 전력 제어 타이머 회로 복잡 |

#### 한줄 요약

- 지연이 심한 전체 뱅크 방식과 지연을 분산하는 뱅크별 방식, 그리고 저전력 대기 환경을 위한 자체 리프레시 모드로 진화해왔다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **꼬리 지연(Tail Latency)**: 실시간 트랜잭션 요청이 하필 리프레시 락업 주기와 겹쳐 응답 지연이 급증하는 치명적인 백분위수 지연 현상이다.
- **로해머(Rowhammer)**: 특정 행을 짧은 시간 내 수백만 번 집중 접근하여 인접 셀 전하를 유출시켜 비트를 반전시키는 보안 취약점 공격이다.
- **표적 행 리프레시(Target Row Refresh)**: 집중 접근되는 인접 행을 하드웨어로 감지하여 추가 충전을 강제함으로써 보안 공격을 방어하는 회로이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 뱅크 리프레시 락업으로 인한 심각한 실시간 **꼬리 지연** 증대 | **뱅크별 리프레시** 체계 도입 및 지능형 뱅크 분산 스케줄링 | 접근 차단 시간 분산 및 지연 시간 대폭 삭감 |
| 특정 행의 비정상적 집중 접근 시 비트가 반전되는 **로해머** 공격 취약점 | 제어기 및 메모리 내부 **표적 행 리프레시** 회로 내장 연동 | 인접 행 강제 충전을 통한 비트 반전 공격 원천 차단 |
| 고온 환경 작동 시 전하 누설 가속으로 인한 치명적인 데이터 파손 한계 | 온도 센서 피드백 연동을 통한 리프레시 충전 간격 단축 제어 | 가혹한 고온 환경에서도 메모리 데이터 보존성 완벽 유지 |
| 초고속 양 엣지 전송 시 신호 타이밍 왜곡으로 인한 데이터 비트 오류 | 시스템 부팅 시 컨트롤러의 읽기/쓰기 훈련 및 동기 신호 조율 | 전기적 데이터 샘플링 여유 확보 및 신호 무결성 보장 |

#### 한줄 요약

- 뱅크별 충전으로 꼬리 지연을 은닉하고 표적 행 충전으로 보안 위협을 차단하며 온도 연동 튜닝으로 신뢰성을 보장한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **리프레시 최적화 기준(Refresh Optimization Criteria)**: 응답 목표 지연시간, 동작 온도, 보안 위협을 종합 평가하여 뱅크별 리프레시 및 표적 충전 파라미터를 확정하는 프레임워크이다.

</details>

- 응답 지연이 핵심이면 **뱅크별 리프레시**, 가혹 환경 및 보안 위협에는 **표적 행 리프레시** 적용

#### 한줄 요약

- 대역폭과 재충전 정지, 보안 요구를 기준으로 시스템 성능을 갉아먹지 않는 최적의 메모리 세대와 스케줄링을 선택해야 한다.
