## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate Synchronous Dynamic RAM)**: 시스템 버스 클록의 상승(Rising)과 하강(Falling) 에지 양측에서 데이터를 전송하여 단일 에지 대비 대역폭을 2배 확장한 동기식 DRAM 기술.
- **더블 엣지 전송(Double-Edge Transfer)**: 클록 상승 에지와 하강 에지에서 각각 데이터를 입출력하여 클록 주파수 변경 없이 데이터 전송률(MT/s)을 2배 높이는 전송 방식.
- **전하 누설(Charge Leakage)**: DRAM 단위 셀(1T1C) 커패시터의 유전체 결함을 통해 저장된 전하가 서서히 방전되어 비트 데이터가 유실되는 물리 현상.
- **리프레시(Refresh)**: 전하가 판독 임계치 이하로 방전되기 전에 전체 행(Row)을 주기적으로 감지 증폭기(Sense Amplifier)로 읽고 재충전하는 데이터 보존 동작.

</details>

- 정의/개념: 클록의 상승·하강 에지 양측에서 데이터를 전송하는 **더블 엣지 전송**과 주기적인 전하 재충전을 수행하는 **리프레시**를 결합하여 고대역폭과 데이터 무결성을 동시 보장하는 동기식 DRAM 구조
- 배경/필요성: 단일 에지 전송(SDR)의 핀당 대역폭 한계 및 DRAM 미세 공정화에 따른 셀 커패시터 자연 방전(데이터 유실)을 극복하기 위해 버스 전송률 2배 확장과 정밀 리프레시 제어 메커니즘 필수화

#### 한줄 요약
- DDR SDRAM은 더블 엣지 전송으로 버스 대역폭을 극대화하고 주기적 리프레시로 휘발성 커패시터 셀의 데이터 무결성을 유지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**: 메모리 내부를 다수의 독립 뱅크(Bank)로 분할하여 특정 뱅크의 지연 구간 동안 타 뱅크의 읽기·쓰기 명령을 중첩 실행하는 구조.
- **버스트 길이(Burst Length, BL)**: 단일 읽기/쓰기 명령 발행 시 내부 프리페치 단위에 맞춰 연속으로 입출력되는 데이터 비트 단위(DDR4: BL8, DDR5: BL16).
- **꼬리 지연(Tail Latency)**: 대다수 요청이 정상 처리되는 중 특정 리프레시 차단 주기와 겹쳐 최악의 응답 지연 시간을 기록하는 상위 99% 이상 지연 현상.

</details>

- **더블 엣지 전송**과 $n$-비트 프리페치를 통해 내부 셀 코어 동작 주파수를 올리지 않고도 외부 버스 핀당 데이터 전송률 2배 확장
- 독립 뱅크 분할을 통한 **뱅크 수준 병렬성** 구조를 채택하여 리프레시를 수행하지 않는 타 뱅크의 정상 읽기·쓰기 요청 중첩 처리 지원
- 커패시터 재충전 수행 시 사이클 시간($t_{RFC}$) 동안 메모리 접근이 차단되어 실시간 대규모 트래픽에서 **꼬리 지연** 유발

#### 한줄 요약
- 더블 엣지 전송과 뱅크 병렬성으로 대역폭을 극대화하되 리프레시 차단 시간($t_{RFC}$)으로 인한 서비스 지연을 완화하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: 호스트 CPU의 읽기·쓰기 요청을 해석하여 JEDEC 타이밍 규격($t_{RCD}, t_{RP}, t_{RFC}$)에 맞춰 명령을 스케줄링하고 주기적 리프레시를 지시하는 하드웨어 유닛.
- **DDR PHY(Physical Layer)**: 제어기 로직과 DRAM 칩 간 고속 전기 신호를 정합하고 데이터 스트로브(DQS) 위상 동기화를 수행하는 물리 계층 인터페이스.
- **감지 증폭기(Sense Amplifier)**: 워드라인 활성화 시 비트라인에 나타난 미세 전압 변화를 감지·증폭하여 행 버퍼에 래치하고 셀 커패시터로 전하를 재충전(Restore)하는 회로.

</details>

```text
[통합 메모리 제어기]
       │
   [DDR PHY]
       │
[DRAM 뱅크 어레이]
       ├─ [감지 증폭기·행 버퍼]
       └─ [온칩 리프레시 회로]
```

선의 의미: `│`는 상하 메모리 버스 인터페이스 연결, 가지(`├─`, `└─`)는 DRAM 내부 핵심 구성요소 소속 관계

| 구성요소 | 책임 |
|:---|:---|
| 메모리 제어기 | 타이밍 규약 기반 읽기·쓰기 중재 및 **리프레시 스케줄링** 지시 |
| DDR PHY | 클록 상승·하강 동기화를 통한 **더블 엣지 전송** 신호 정합 및 위상 정렬 |
| 감지 증폭기·행 버퍼 | 비트라인 미세 전압 증폭, 데이터 래치 및 셀 **전하 재충전** 수행 |
| 온칩 리프레시 회로 | 행 주소 카운터를 자동 순환시켜 $t_{RFC}$ 동안 **셀 전하 복원** 제어 |

#### 한줄 요약
- 메모리 제어기의 명령 스케줄링과 DDR PHY의 신호 정합, 온칩 리프레시 회로의 자율 행 카운팅이 유기적으로 결합되어 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **tREFI(Refresh Interval Time)**: 메모리 제어기가 리프레시 명령을 발행해야 하는 평균 주기(표준 $7.8\mu s$, 고온 환경 $3.9\mu s$).
- **tRFC(Refresh Cycle Time)**: 단일 리프레시 명령 수행 시 커패시터 재충전 완료까지 해당 메모리 접근이 차단되는 시간(수백 ns).

</details>

```text
[메모리 제어기: tREFI 리프레시 주기 타이머 만료]
                       │
                       ▼
          1. 리프레시 제어 방식 판정
            ┌──────────┴──────────┐
   (전체 뱅크 방식)               (뱅크별 방식)
            │                             │
            ▼                             ▼
2. 전체 뱅크 REF 명령 전송    3. 대상 뱅크 단일 PB-REF 전송
            │                             │
            ▼                             ▼
4. 전 메모리 접근 차단        5. 해당 뱅크만 국소 차단
   (tRFC 동안 긴 꼬리 지연)      (타 뱅크 정상 접근 허용)
            │                             │
            └──────────┬──────────────────┘
                       │
                       ▼
[커패시터 전하 재충전 완료 후 일반 읽기/쓰기 스케줄링 재개]
```

분기 결과: **전체 뱅크 리프레시**는 전 영역 접근 차단으로 꼬리 지연이 심화되며, **뱅크별 리프레시**는 타 뱅크 접근을 허용하여 대역폭 가용성을 유지함

**동작 원리**

1. **리프레시 제어 방식 판정**: 메모리 제어기가 $t_{REFI}$ 주기 도래 시 워크로드 특성에 따라 전체 뱅크 일괄 재충전 또는 뱅크별 순차 재충전 모드를 결정함
2. **전체 뱅크 REF 명령 전송**: 표준 리프레시 모드에서 명령 버스를 통해 장착된 모든 DRAM 뱅크로 브로드캐스트 리프레시 신호를 전달함
3. **대상 뱅크 단일 PB-REF 전송**: 세분화 리프레시 모드에서 특정 뱅크 주소를 지정하여 해당 뱅크로만 국소 리프레시 명령을 인가함
4. **전 메모리 접근 차단**: 전체 뱅크 리프레시가 수행되는 $t_{RFC}$ 시간 동안 호스트 프로세서의 모든 메모리 입출력 요청을 대기 큐에 보류함
5. **해당 뱅크만 국소 차단**: 뱅크별 리프레시 수행 중 대상 뱅크만 차단하고 나머지 독립 뱅크에 대해서는 정상 버스트 읽기·쓰기 처리를 지속함

#### 한줄 요약
- 주기적 타이머 만료 시 모드 판정에 따라 전 뱅크 차단 또는 개별 뱅크 국소 차단을 거쳐 커패시터 전하를 재충전한다.

## Ⅴ. 종류 및 비교

| DRAM 리프레시 방식 | 전체 뱅크 리프레시 | 뱅크별 리프레시 | 자체 리프레시 |
|:---|:---|:---|:---|
| 적용 기준 | **제어 로직 단순화** 최우선 시스템 | **실시간 응답성 보장** 및 지연 분산 요구 | **시스템 대기 상태** 및 초저전력 요구 |
| 핵심 특징 | 전체 뱅크 대상 **일괄 동시 리프레시** | 독립 뱅크 단위의 **순차적 국소 리프레시** | 외부 클록 차단 후 **온칩 자율 리프레시** |
| 한계 | $t_{RFC}$ 동안 전체 버스 접근 전면 차단 | 제어기 명령 스케줄링 복잡도 증가 | 외부 접근 불가 및 정상 모드 복귀 지연 발생 |

#### 한줄 요약
- 단순 제어에는 전체 뱅크 리프레시가 쓰였으나 실시간 꼬리 지연을 줄이기 위해 뱅크별 리프레시와 저전력 자체 리프레시가 채택된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표적 행 리프레시(Targeted Row Refresh, TRR)**: 특정 행의 반복 활성화(Row Hammer 공격) 감지 시 인접 행들을 선제적으로 추가 재충전하여 전하 유출을 방어하는 기법.
- **오류 정정 코드(Error-Correcting Code, ECC)**: 데이터 저장 및 전송 중 발생하는 비트 반전(Bit Flip) 오류를 검출하고 스스로 정정하여 메모리 데이터 무결성을 보장하는 기술.
- **온다이 오류 정정 코드(On-Die Error-Correcting Code, On-Die ECC)**: DRAM 제어기와의 전송 버스 구간이 아닌 실리콘 다이 내부 셀 어레이에서 미세 공정 전하 누설로 발생하는 단일 비트 오류를 칩 내부에서 자체 정정하는 회로 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 리프레시 집중으로 인한 실시간 대규모 트래픽의 심각한 꼬리 지연 | **뱅크별 리프레시** 및 비동기 분산 스케줄링 적용 | $t_{RFC}$ 차단 구간 분산 및 최악 응답 지연 60% 이상 단축 |
| 인접 워드라인 반복 토글 및 셀 미세화로 인한 물리적 비트 플립 결함 | **표적 행 리프레시** 모니터링 및 **온다이 ECC** 탑재 | 인접 행 전하 선제 복원 및 단일 비트 오류 자체 정정 |
| 고온 환경($>85^\circ\text{C}$) 노출 시 커패시터 누설 전류 급증 | 온도 센서 연동 **가변 주기 리프레시** 기법 적용 | 고온 구간 $t_{REFI}$ 주기 2배 단축($3.9\mu s$)을 통한 데이터 보존 무결성 유지 |

#### 한줄 요약
- 실무에서는 뱅크별 분산 스케줄링으로 꼬리 지연을 방어하고 표적 행 리프레시와 온다이 ECC로 물리 계층 신뢰성을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **저전력 더블 데이터 레이트 5(Low Power Double Data Rate 5, LPDDR5)**: 저전압(0.5V~1.05V) 동작과 동적 전압/주파수 스케일링(DVFS) 및 뱅크별 리프레시를 지원하여 전력 소모를 최소화한 모바일·엣지 디바이스용 고속 메모리 규격.
- **직렬 접속 메모리 모듈(Dual In-line Memory Module, DIMM)**: 복수의 DRAM 칩을 단일 PCB 기판 양면에 실장하고 독립된 신호 핀으로 64비트(ECC 포함 72/80비트) 채널을 구성하는 컴퓨터 주기억장치 표준 모듈 규격.
- **다중 랭크 버퍼 메모리 모듈(Multi-Rank Dual In-line Memory Module, MRDIMM)**: 단일 DIMM 모듈 상에서 복수 랭크의 데이터를 멀티플렉서 버퍼(Mux)로 결합하여 호스트 버스 대역폭을 2배로 확장하는 차세대 고대역폭 서버용 메모리 모듈 규격.
- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 고속 PCIe 5.0/6.0 물리 계층을 기반으로 CPU와 메모리 확장 장치 간 캐시 일관성과 메모리 풀링을 지원하는 개방형 인터커넥트 규격.

</details>

- DDR5 및 LPDDR5 표준에서 **더블 엣지 전송**과 **뱅크별 리프레시**, **온다이 ECC**가 기본 규격으로 안착하였으며, 대규모 AI 인프라에서는 **CXL 풀드 메모리**와 MRDIMM 아키텍처를 결합해 리프레시 지연을 은닉하는 구조로 진화 추세
- 실무 메모리 제어기 설계 시 단순 피크 대역폭 지표에 매몰되지 않고, $t_{RFC}$ 차단 시간이 실시간 서비스의 꼬리 지연에 미치는 영향을 정량화하여 **비동기 분산 리프레시 스케줄링**을 우선 적용하는 통찰 필요

#### 한줄 요약
- 리프레시 지연은 CXL·MRDIMM 계층에서 은닉되는 추세이며, 제어기 설계 시 피크 대역폭보다 꼬리 지연을 줄이는 분산 스케줄링이 핵심 통찰이다.
