## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DDR SDRAM(Double Data Rate Synchronous Dynamic Random-Access Memory)**: 클록의 상승·하강 양 엣지에서 데이터를 전송하는 동기식 DRAM입니다.
- **전하 누설(Charge Leakage)**: DRAM 커패시터의 저장 전하가 시간에 따라 감소하는 현상입니다.
- **리프레시(Refresh)**: 누설되기 전 행의 전하를 다시 충전해 데이터를 보존하는 동작입니다.

</details>

- 정의/개념: 양 엣지 전송과 리프레시를 사용하는 **고대역폭 동기식 DRAM**
- 배경/필요성: 전송 대역폭과 커패시터 데이터 보존의 동시 확보

#### 한줄 요약

- DDR은 한 클록에서 데이터를 두 번 보내고, DRAM은 전하가 사라지기 전에 반복 충전해 저장값을 유지합니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **뱅크 수준 병렬성(Bank-Level Parallelism, BLP)**: 여러 메모리 뱅크를 독립적으로 활용해 요청을 겹치는 구조입니다.
- **버스트 길이(Burst Length)**: 하나의 명령으로 연속 전송하는 데이터 단위의 수입니다.
- **양 엣지 전송(Double-Edge Transfer)**: 클록의 두 전이 시점에서 데이터를 전달하는 방식입니다.

</details>

- 양 엣지 전송에 따른 **핀당 전송률 향상**
- 뱅크 병렬성에 따른 **요청 중첩**
- 리프레시 동안 발생하는 **접근 차단 비용**

#### 한줄 요약

- DDR은 전송 시점을 늘려 대역폭을 얻고, 뱅크를 나누어 요청을 겹치지만, 리프레시가 진행되는 동안 일부 접근은 기다려야 합니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 제어기(Memory Controller)**: DRAM 명령, 주소, 타이밍과 리프레시를 스케줄링하는 제어기입니다.
- **DDR PHY(DDR Physical Interface)**: 제어기와 DRAM 사이의 고속 전기 신호를 송수신하고 타이밍을 맞추는 인터페이스입니다.
- **행 버퍼(Row Buffer)**: 활성화된 DRAM 행의 데이터를 감지해 열 접근을 빠르게 하는 버퍼입니다.

</details>

```text
[DDR SDRAM 시스템]
├─ 메모리 제어기
├─ DDR PHY
└─ DRAM 배열
   ├─ 뱅크·행 버퍼
   └─ 리프레시 제어
```

| 구성요소 | 책임 |
|:---|:---|
| 메모리 제어기 | 읽기·쓰기·리프레시 명령 스케줄링 |
| DDR PHY | 고속 데이터 신호와 샘플링 타이밍 관리 |
| 뱅크·행 버퍼 | 행 활성화와 열 데이터 접근 |
| 리프레시 제어 | 누설 전하의 주기적 복원 |

#### 한줄 요약

- 제어기가 명령 순서를 정하고 PHY가 신호를 맞추며, DRAM 내부 뱅크와 리프레시 회로가 실제 저장을 담당합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **리프레시 간격(tREFI)**: 리프레시 명령 사이에 허용되는 기준 간격입니다.
- **리프레시 사이클 시간(tRFC)**: 리프레시 명령이 수행되는 동안 일반 접근이 제한되는 시간입니다.
- **프리차지(Precharge)**: 다음 행을 열기 전에 뱅크를 기준 상태로 되돌리는 동작입니다.

</details>

```text
[1. 제어기 타이머 확인]
          │
          ├─ 리프레시 시점 → [2. 행 전하 복원]
          │                         │
          │                         ▼
          │                    [3. 접근 재개]
          │
          └─ 일반 접근 → [2. 행 활성화·열 전송·프리차지]
```

동작 원리:

1. 제어기 타이머 확인: tREFI 도래와 요청 큐 상태 확인
2. 행 전하 복원 또는 행 활성화·열 전송·프리차지: 리프레시·일반 접근 선택
3. 접근 재개: tRFC 동안 제한된 뱅크의 접근을 다시 허용

#### 한줄 요약

- 컨트롤러는 먼저 리프레시가 늦지 않았는지 보고, 아니면 일반 요청을 처리하며, 리프레시가 끝난 뒤 접근을 재개합니다.

## Ⅴ. 종류 및 비교

| 리프레시 방식 | 전체 뱅크 | 뱅크별 | 자체 리프레시 |
|:---|:---|:---|:---|
| 적용 기준 | 단순한 제어 우선 | 접근 차단 분산 필요 | 저전력 대기 상태 |
| 핵심 특징 | 넓은 범위를 한 번에 복원 | 일부 뱅크 중심 복원 | DRAM 내부에서 주기적 복원 |
| 한계 | 넓은 접근 차단과 꼬리 지연 | 스케줄링 복잡도 증가 | 일반 접근이 제한되는 대기 상태 |

#### 한줄 요약

- 짧은 제어가 중요하면 전체 범위를 단순히 관리하고, 지연 분산이 중요하면 뱅크별 리프레시를 사용합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표적 행 리프레시(Target Row Refresh, TRR)**: 특정 행의 반복 활성화로 인접 행 오류가 우려될 때 주변 행을 추가로 복원하는 완화 기법입니다.
- **메모리 트레이닝(Memory Training)**: 부팅 때 데이터 신호와 샘플링 타이밍을 맞추는 초기화 절차입니다.
- **오류 정정 코드(Error Correcting Code, ECC)**: 저장 데이터 오류를 검출하고 일부 오류를 정정하는 코드입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전체 리프레시가 긴 꼬리 지연 유발 | 뱅크별 리프레시와 요청 스케줄 조정 | 접근 차단 범위 분산 |
| 특정 행 반복 접근으로 인접 행 오류 | TRR과 ECC 적용 범위 검증 | 데이터 오류 가능성 완화 |
| 고온에서 전하 누설 증가 | 온도 기반 리프레시 간격 조정 | 데이터 보존 여유 확보 |
| 고속 양 엣지 신호의 타이밍 오류 | 메모리 트레이닝과 신호 무결성 검증 | 샘플링 오류 감소 |

#### 한줄 요약

- DDR 성능은 전송률만 높이는 문제가 아니라, 리프레시 차단과 신호 오류를 워크로드와 온도 조건에서 함께 통제하는 문제입니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **꼬리 지연(Tail Latency)**: 평균이 아니라 일부 요청에서 발생하는 가장 긴 지연 구간입니다.

</details>

- 지연 민감 작업은 **꼬리 지연**과 리프레시 차단이 작은 방식을 선택하고, 대역폭 중심 작업은 뱅크 병렬성과 양 엣지 전송을 우선해 신뢰성 대책까지 확정

#### 한줄 요약

- DDR 설계는 빠른 데이터 전송과 리프레시로 인한 대기, 고속 신호의 오류 가능성을 함께 비교해 정해야 합니다.
