## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **JTAG(Joint Test Action Group, IEEE 1149.1)**: 집적회로(IC)의 핀 결선 테스트(경계 스캔)와 펌웨어 플래싱 및 온칩 디버깅을 지원하는 표준 하드웨어 인터페이스.
- **경계 스캔(Boundary Scan)**: IC 내부 로직과 외부 I/O 핀 사이에 스캔 셀(Scan Cell)을 배치하여 물리적 접촉 없이 직렬 통신만으로 핀의 전압 상태를 읽고 쓰는 테스트 기법.

</details>

- 정의/개념: **경계 스캔(Boundary Scan)** 셀을 통해 물리적 접촉 없이 배선을 검사하고 온칩 디버깅까지 지원하는 **JTAG(Joint Test Action Group, IEEE 1149.1)** 인터페이스
- 배경/필요성: 칩 아래에 숨은 납땜 접점은 프로브가 닿지 않고 핀 수가 늘수록 수동 검사가 비용과 누락 모두에서 감당되지 않음

#### 한줄 요약
- 이 표준이 푼 문제는 검사 정밀도가 아니라 접근 불가능성이며, 눈으로도 프로브로도 닿을 수 없는 지점을 칩 스스로 보고하게 만든 발상이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **TAP(Test Access Port) 컨트롤러**: TMS와 TCK 신호의 변화에 따라 동작하는 16개 상태를 가진 유한 상태 기계(FSM).
- **BSDL(Boundary Scan Description Language)**: 특정 IC의 경계 스캔 구조와 명령어, 핀 매핑 정보를 정의한 표준 텍스트 파일.

</details>

- 클록·모드·입력·출력 네 신호선만으로 동작하는 직렬 결선
- **TAP(Test Access Port) 컨트롤러**가 16개 상태 전이로 모든 동작을 순서화
- 여러 칩을 직렬로 엮어 단일 헤더로 보드 전체를 검사

#### 한줄 요약
- 신호선을 극단적으로 줄인 대가로 모든 데이터가 직렬로 흐르므로, 검사 시간은 칩 수와 스캔 길이에 비례해 늘어난다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IR(Instruction Register)**: 실행할 테스트 명령어(EXTEST, SAMPLE, BYPASS 등)를 저장하는 레지스터.
- **DR(Data Register)**: BSR, BYPASS, IDCODE 등 실제 테스트 데이터가 시프트되는 레지스터 그룹.

</details>

```text
[JTAG TAP 구조]
├─ 신호 핀
│  ├─ TCK (클록)·TMS (상태 제어)
│  └─ TDI (직렬 입력)·TDO (직렬 출력)
├─ TAP 컨트롤러 (16상태 유한 상태 기계)
└─ 레지스터
   ├─ 명령어 레지스터 (실행할 테스트 명령 보관)
   └─ 데이터 레지스터
      ├─ 경계 스캔 레지스터 (I/O 핀 구동·캡처)
      ├─ 디바이스 ID 레지스터
      └─ 바이패스 레지스터 (1비트 통과 경로)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 입력에서 출력까지 한 줄로 이어지는 직렬 경로가 어느 레지스터를 지날지는 상태 기계가 결정

| 구성요소 | 책임 |
|:---|:---|
| 신호 핀 4종 | 클록·상태 선택·직렬 입력·직렬 출력 제공 |
| TAP 컨트롤러 | 상태 전이로 캡처·시프트·갱신 순서 제어 |
| **IR(Instruction Register)** | 실행할 테스트 명령어 보관 |
| 경계 스캔 레지스터 | I/O 패드마다 배치된 셀로 핀 구동·값 읽기 |
| 바이패스 레지스터 | 대상이 아닌 칩의 경로를 1비트로 단축 |

#### 한줄 요약
- **DR(Data Register)** 여러 개가 같은 직렬 경로를 나눠 쓰기 때문에 바이패스 레지스터가 성능 장치가 되며, 구조의 단순함이 곧 최적화 대상이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **EXTEST**: 칩 내부 로직과 핀을 분리하고 경계 스캔 셀을 통해 칩 외부 PCB 배선의 단선/단락을 검사하는 명령어.

</details>

```text
테스트 장비 연결 후 모든 칩 TAP 리셋
        │
   이 칩이 검사 대상인가?
   ┌────┴─────┐
아니오          예
   │             │
바이패스 명령   외부 결선 검사 명령 적재
(1비트 통과)      │
   │        핀 구동용 테스트 패턴을 스캔 셀에 주입
   │             │
   │        수신 칩 스캔 셀이 한 클록에 전압 캡처
   └────┬────────┘
        │
   캡처 비트열을 직렬 출력으로 인출
        │
   회로 넷리스트와 일치하는가?
   ┌────┴─────┐
  예           아니오
   │             │
정상 판정      단선·단락 위치 특정
```

분기 결과: 검사 대상이 아닌 칩을 1비트로 건너뛰게 하는 선택이 전체 스캔 길이를 좌우하므로, 진단 시간은 보드 규모가 아니라 체인 구성 방식이 결정

#### 한줄 요약
- **EXTEST**가 칩 내부 로직을 끊고 핀만 다룬다는 점이 이 검사의 핵심이며, 그래서 칩이 정상인지와 무관하게 배선만 따로 판정할 수 있다.

## Ⅴ. 종류 및 비교

| 하드웨어 디버그 인터페이스 | JTAG (IEEE 1149.1) | SWD (Serial Wire Debug) | UART | In-Circuit Emulator (ICE) |
|:---|:---|:---|:---|:---|
| 적용 기준 | PCB 보드 결선 검사 및 복수 칩 체인 | Arm Cortex-M 초소형 핀 제약 디버깅 | 콘솔 로그 출력 및 단순 직렬 통신 | 레거시 CPU 하드웨어 전용 에뮬레이션 |
| 핵심 특징 | 4선(TCK/TMS/TDI/TDO) 및 경계 스캔 | 2선(SWCLK/SWDIO) 직렬 양방향 디버깅 | 2선(TX/RX) 비동기 문자열 전송 | CPU 소켓을 직접 대체해 실시간 분석 |
| 한계 | 많은 핀 수(4~5핀) 소모 및 복잡한 FSM | 경계 스캔(보드 결선 검사) 기능 미지원 | CPU 레지스터 직접 제어/브레이크 불가 | 극심한 고비용 및 현대 BGA 칩 적용 불가 |

#### 한줄 요약
- 네 인터페이스는 핀 수와 기능 범위를 맞바꾼 눈금이며, 핀을 아끼려 SWD로 내려가면 보드 결선 검사 능력이 함께 사라진다는 점이 결정적 손실이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **JTAG 보안 잠금(JTAG Fuse/Lock)**: 상용 제품 양산 출하 시 eFuse를 끊거나 암호 인증을 걸어 해커가 JTAG으로 펌웨어를 추출하지 못하도록 차단하는 보안 조치.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 출하 후 디버그 포트로 펌웨어 추출·변조 | 수명주기 상태별 인증 디버그 또는 **JTAG 보안 잠금(JTAG Fuse/Lock)** 적용 | 정비 요구와 비인가 접근 차단의 절충 |
| 체인 중 한 칩의 고장이 전체 검사를 마비 | 체인을 분할하고 정상 칩은 바이패스로 우회 | 고장 구간 격리와 스캔 길이 단축 |
| 긴 케이블에서 클록 신호 반사·노이즈 발생 | 종단 저항과 슈미트 트리거 버퍼 장착 | 신호 무결성 확보와 오판정 감소 |
| 납땜 불량이 간헐적으로만 드러남 | **BSDL(Boundary Scan Description Language)** 기반 스캔과 전기·기능 검사 병행 | 사각지대 보완으로 검출률 향상 |

#### 한줄 요약
- 같은 포트가 생산에서는 검사 수단이고 출하 후에는 침입 경로가 되므로, 이 인터페이스의 관리는 기술 문제가 아니라 수명주기 정책 문제다.

## Ⅶ. 결론

- 프로브가 닿지 않는 PCB 결선 검사는 JTAG, 핀 제약이 심한 마이크로컨트롤러 디버깅은 SWD를 선택하고, 출하 제품은 일괄 영구 잠금 대신 위협 모델과 현장 수리 정책에 맞춘 인증 디버그 수명주기를 적용

#### 한줄 요약
- 포트를 영구히 끊으면 보안은 확실해지지만 현장 수리와 고장 분석의 길도 함께 끊기므로, 잠금 정책은 보안팀만이 아니라 서비스 조직과 함께 정해야 한다.
