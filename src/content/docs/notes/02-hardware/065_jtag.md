## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **JTAG(Joint Test Action Group, IEEE 1149.1)**: 집적회로(IC)의 핀 결선 테스트(경계 스캔)와 펌웨어 플래싱 및 온칩 디버깅을 지원하는 표준 하드웨어 인터페이스.
- **경계 스캔(Boundary Scan)**: IC 내부 로직과 외부 I/O 핀 사이에 스캔 셀(Scan Cell)을 배치하여 물리적 접촉 없이 직렬 통신만으로 핀의 전압 상태를 읽고 쓰는 테스트 기법.

</details>

- 정의/개념: PCB 보드 상의 칩 간 배선 단락/단선 검사와 임베디드 MCU의 온칩 디버깅을 위해 **경계 스캔(IEEE 1149.1)** 을 수행하는 표준 직렬 테스트 인터페이스
- 배경/필요성: BGA의 내부 납땜 접점은 프로브로 접근하기 어렵고 다핀 보드의 단선·단락을 수동 검사하기에는 비용과 누락 증가

#### 한줄 요약
- 칩 핀에 침을 꽂지 않고도 4개의 전용 신호선으로 칩 내부의 연결 상태를 검사하고 펌웨어를 디버깅하는 표준 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **TAP(Test Access Port) 컨트롤러**: TMS와 TCK 신호의 변화에 따라 동작하는 16개 상태를 가진 유한 상태 기계(FSM).
- **BSDL(Boundary Scan Description Language)**: 특정 IC의 경계 스캔 구조와 명령어, 핀 매핑 정보를 정의한 표준 텍스트 파일.

</details>

- **4선(TCK, TMS, TDI, TDO)** 및 선택적 리셋(TRST) 기반 초간소화 직렬 결선
- 16개 상태를 갖는 **TAP(Test Access Port) 컨트롤러 FSM** 구동
- 복수 칩을 데이지 체인(Daisy Chain)으로 연결하여 단일 헤더로 보드 전체 검사 가능

#### 한줄 요약
- 4개의 핀(클록, 모드, 데이터 입력, 출력)과 16상태 FSM을 통해 보드 전체 칩을 줄줄이 엮어 검사한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IR(Instruction Register)**: 실행할 테스트 명령어(EXTEST, SAMPLE, BYPASS 등)를 저장하는 레지스터.
- **DR(Data Register)**: BSR, BYPASS, IDCODE 등 실제 테스트 데이터가 시프트되는 레지스터 그룹.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ JTAG TAP 아키텍처 및 내부 레지스터 구조                    │
│                                                             │
│  [ TCK (클록) ] ──┐                                         │
│  [ TMS (상태제어) ]┴──► [ TAP 컨트롤러 (16-State FSM) ]     │
│                              │                              │
│                     ┌────────┴────────┐                     │
│                     │ MUX 제어 신호   │                     │
│                     ▼                 ▼                     │
│  [ TDI (데이터 입력) ]                                      │
│    ├──► [ 명령어 레지스터 (Instruction Register, IR) ] ──┐  │
│    │                                                     │  │
│    └──► [ 데이터 레지스터 (Data Registers, DR) ]         │  │
│          ├─► 경계 스캔 레지스터 (BSR) ──► [I/O 핀 제어]  │  │
│          ├─► 디바이스 ID 레지스터 (IDCODE)               ├──┤
│          └─► 바이패스 레지스터 (BYPASS, 1-bit)           │  │
│                                                          │  │
│                                       [ 출력 MUX ] ──────┴─► [ TDO (출력) ]
└─────────────────────────────────────────────────────────────┘
```

선의 의미: TMS/TCK가 TAP 상태를 전환하면 TDI로 들어온 데이터가 IR 또는 DR을 통과하여 TDO로 직렬 출력됨

| 구성요소 | 책임 |
|:---|:---|
| TCK / TMS / TDI / TDO | 클록(TCK), 상태선택(TMS), 직렬입력(TDI), 직렬출력(TDO) 기본 4대 신호 핀 |
| TAP 컨트롤러 | 16개 상태 전이 FSM으로 Capture, Shift, Update 동작을 정밀 제어 |
| 명령어 레지스터 (IR) | EXTEST(외부 결선 검사), SAMPLE(신호 캡처), BYPASS(통과) 명령어 저장 |
| 경계 스캔 레지스터 (BSR) | 각 I/O 패드에 직렬 배치된 스캔 셀들로 핀 상태 강제 구동 및 입력값 읽기 |
| 바이패스 레지스터 (BYPASS) | 테스트 대상이 아닌 칩의 데이터 경로를 1비트로 단축시켜 체인 지연 최소화 |

#### 한줄 요약
- TAP 컨트롤러, IR/DR 레지스터, BSR 스캔 셀, 4대 전용 핀이 하나의 테스트 아키텍처를 형성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **EXTEST**: 칩 내부 로직과 핀을 분리하고 경계 스캔 셀을 통해 칩 외부 PCB 배선의 단선/단락을 검사하는 명령어.

</details>

```text
JTAG 테스트 장비(JTAG Tester) 연결 및 전원 인가
      │
      ▼
1. 상태 리셋
      │
      ▼
2. 명령어 시프트
      │
      ▼
3. 벡터 주입
      │
      ▼
4. 신호 캡처
      │
      ▼
5. 결과 분석
```

**동작 원리**

1. **상태 리셋**: TMS를 High로 유지하며 클록을 인가해 모든 칩의 TAP을 리셋 상태로 동기화
2. **명령어 시프트**: IR 스캔 경로를 선택하여 검사할 명령어(EXTEST)를 체인 상의 모든 칩에 전달
3. **벡터 주입**: DR 스캔 경로로 전환 후 송신 칩의 핀들을 구동할 1/0 테스트 패턴을 비트 단위 전송
4. **신호 캡처**: PCB 배선을 통해 전달된 전압 레벨을 수신 칩의 경계 스캔 셀이 1클록 순간에 캡처
5. **결과 분석**: 캡처된 비트열을 TDO 핀으로 순차 인출하여 회로도 넷리스트(Netlist)와 일치 여부 비교

#### 한줄 요약
- TAP 리셋 → 명령어(EXTEST) 로드 → 테스트 패턴 주입 → 핀 캡처 → TDO 결과 비교 순으로 배선을 진단한다.

## Ⅴ. 종류 및 비교

| 하드웨어 디버그 인터페이스 | JTAG (IEEE 1149.1) | SWD (Serial Wire Debug) | UART | In-Circuit Emulator (ICE) |
|:---|:---|:---|:---|:---|
| 적용 기준 | PCB 보드 결선 검사 및 복수 칩 체인 | Arm Cortex-M 초소형 핀 제약 디버깅 | 콘솔 로그 출력 및 단순 직렬 통신 | 레거시 CPU 하드웨어 전용 에뮬레이션 |
| 핵심 특징 | 4선(TCK/TMS/TDI/TDO) 및 경계 스캔 | 2선(SWCLK/SWDIO) 직렬 양방향 디버깅 | 2선(TX/RX) 비동기 문자열 전송 | CPU 소켓을 직접 대체해 실시간 분석 |
| 한계 | 많은 핀 수(4~5핀) 소모 및 복잡한 FSM | 경계 스캔(보드 결선 검사) 기능 미지원 | CPU 레지스터 직접 제어/브레이크 불가 | 극심한 고비용 및 현대 BGA 칩 적용 불가 |

#### 한줄 요약
- 보드 결선 검사는 JTAG, Arm 마이크로 디버깅은 SWD, 콘솔 통신은 UART, 레거시 분석은 ICE를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **JTAG 보안 잠금(JTAG Fuse/Lock)**: 상용 제품 양산 출하 시 eFuse를 끊거나 암호 인증을 걸어 해커가 JTAG으로 펌웨어를 추출하지 못하도록 차단하는 보안 조치.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제품 출하 후 JTAG를 통한 **펌웨어 추출·변조 위험** | 수명주기 상태별 인증 디버그 또는 eFuse 잠금 적용 | 생산·정비 요구와 비인가 디버그 차단 절충 |
| 다중 칩 체인의 **단일 칩·배선 고장 영향 확대** | 체인을 분할하고 우회 가능한 정상 칩은 BYPASS 사용 | 고장 구간 격리와 스캔 길이 단축 |
| 긴 JTAG 케이블 사용 시 **TCK 클록 신호 반사 및 노이즈 오류** | TCK 라인에 **종단 저항(Series Termination)** 및 슈미트 트리거 버퍼 장착 | 신호 무결성(Signal Integrity) 보장 |
| BGA 납땜 불량에 따른 **간헐적 연결 오류** | BSDL·넷리스트 기반 경계 스캔과 전기·기능 검사 병행 | 경계 스캔 사각지대를 보완해 결함 검출률 향상 |

#### 한줄 요약
- eFuse로 해킹을 막고, BYPASS로 체인을 보호하며, 종단 저항과 자동 BSDL로 BGA 불량을 잡아낸다.

## Ⅶ. 결론

- 접근 곤란한 PCB 결선 검사는 **JTAG**, 핀 제약 Arm 디버깅은 SWD 선택
- 출하 제품은 무조건 영구 잠금하지 말고 위협 모델·현장 수리 정책에 따라 인증 디버그 수명주기 적용

#### 한줄 요약
- 경계 스캔 표준 아키텍처를 통해 PCB 하드웨어 결함을 완벽히 진단하고, 양산 단계에서는 JTAG 포트를 잠가 보안을 달성해야 한다.
