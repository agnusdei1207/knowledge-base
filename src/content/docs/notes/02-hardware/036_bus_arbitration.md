## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **버스 중재(Bus Arbitration)**: 여러 마스터 요청 중 하나에 공유 버스 사용권을 배타적으로 승인하는 제어 기법.
- **CPU(Central Processing Unit)**: 버스 트랜잭션을 발생시키는 중앙 처리 장치.
- **DMA(Direct Memory Access)**: 메모리 직접 전송을 위해 버스 점유를 요청하는 입출력 제어기.
- **버스 마스터(Bus Master)**: 중재 승인 후 버스 트랜잭션을 직접 시작하는 주체.

</details>

- 정의/개념: 여러 마스터의 동시 요청을 평가해 특정 시점에 단 하나의 버스 사용권만 승인하는 **버스 중재** 기법
- 배경/필요성: 다중 버스 마스터 환경에서 동시 구동 시 신호 충돌(Collision) 및 데이터 훼손 발생 방지

#### 한줄 요약

- 버스 중재기는 동시 요청 중 하나의 마스터만 승인해 공유 버스의 신호 충돌을 방지한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **배타적 소유권(Exclusive Ownership)**: 특정 시점에 하나의 마스터만 버스를 구동할 수 있도록 제어하는 권한.
- **버스트 길이(Burst Length)**: 단일 중재 승인으로 연속 전송 가능한 데이터 블록의 크기.
- **에이징(Aging)**: 오래 대기한 저순위 요청의 우선순위를 단계적으로 높여 기아를 막는 기법.
- **우선순위(Priority)**: 경합 시 먼저 승인할 대상을 정하는 등급 서열.
- **버스트 한도(Burst Limit)**: 단일 전송 점유로 인한 버스 독점을 막는 최댓값.

</details>

- 다중 마스터의 동시 구동을 차단하는 **배타적 소유권** 보장
- **우선순위** 및 **버스트 한도** 설정에 따른 대기 시간 결정
- 저우선순위 요청의 무한 대기를 방지하는 **에이징** 기법 적용

#### 한줄 요약

- 우선순위와 버스트 한도는 긴급 요청의 지연을 제한하고, 에이징은 오래 기다린 저순위 요청의 기아를 방지한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **요청 신호(Bus Request Signal, BREQ)**: 버스 마스터가 중재기에 사용 권한을 요구하는 신호.
- **승인 신호(Bus Grant Signal, BGRT)**: 중재기가 지정된 마스터에게 버스 권한을 부여하는 신호.
- **중재기(Bus Arbitrator)**: 설정된 정책에 따라 요청을 평가하여 배타적 승인을 내리는 제어 장치.
- **공유 버스(Shared Bus)**: 승인된 마스터의 주소·제어·데이터 신호를 전달하는 공통 물리 경로.

</details>

```text
[버스 마스터 집합] ----- [중재기] ----- [공유 버스]
```

선의 의미: 요청•승인 신호와 배타적 버스 사용권을 공유하는 인접 구성요소 간의 정적 중재 경계.

| 구성요소 | 책임 |
|:---|:---|
| 버스 마스터 집합 | 사용 권한 요청 및 승인 후 데이터 전송 |
| 중재기 | 정책 기반 단일 승인 대상 선택 및 권한 부여 |
| 공유 버스 | 승인된 마스터 대상 배타적 신호 전달 경로 |

#### 한줄 요약

- 여러 마스터가 요청하면 중재기가 하나만 승인해 공유 버스의 충돌을 막는다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **경합 상태(Contention State)**: 둘 이상의 버스 마스터가 동일 시점에 사용권을 동시에 요구한 상태.
- **시간 할당량(Time Slice)**: 단일 마스터가 연속 점유할 수 있도록 허용된 최대 전송 시간.
- **사용권 반납(Bus Release)**: 전송 완료 후 점유를 해제하여 후속 대기 요청 승인을 가능케 하는 동작.

</details>

```text
                  [CPU•DMA 동시 요청]
                            |
                    1. 요청 상태 수집
                            |
               2. 정책 판정•단일 마스터 승인
                    /               \
               [승인 마스터]       [비승인 대기]
                    |                    |
      +-----------------------------+    |
      | 반복: 허용 버스트•할당량   |    |
      | 3. 승인 마스터 버스 전송    |    |
      +-----------------------------+    |
                    |                    |
                 4. 사용권 반납          |
                    |                    |
                    +---------+----------+
                              |
                     5. 다음 마스터 승인
                              |
                         [전송 순환]
```

### 동작 원리

1. **요청 상태 수집**: CPU·DMA 등 마스터의 **요청 신호** 수집 및 경합 상태 감지.
2. **정책 판정·단일 승인**: 고정 우선순위·라운드 로빈·에이징 정책 적용 후 단일 마스터 승인.
3. **배타적 버스 전송**: 승인된 마스터의 **버스트 길이** 및 **시간 할당량** 이내 배타적 전송 수행.
4. **사용권 반납**: 전송 완료 또는 할당 시간 만료 시 **사용권 반납** 및 점유 해제.
5. **다음 마스터 승인**: 남은 대기 요청 재평가 후 후속 마스터 승인 및 순환.

#### 한줄 요약

- 중재기는 동시 요청 중 하나만 승인하고, 버스트 한도가 끝나면 사용권을 회수해 다음 대기 요청을 다시 평가한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **중앙 집중식 중재(Centralized Arbitration)**: 단일 중재기가 모든 요청 신호를 집중 수신하여 결정하는 방식.
- **분산식 중재(Distributed Arbitration)**: 각 마스터가 자체 제어 논리와 공동 신호선을 통해 승인을 직접 결정하는 방식.
- **단일 장애점(Single Point of Failure, SPOF)**: 해당 요소 고장 시 전체 버스 중재 기능이 마비되는 지점.
- **판정 지연(Arbitration Latency)**: 사용 요청 후 최종 승인 신호를 수신할 때까지 걸리는 지연 시간.

</details>

| 버스 중재 방식 | 중앙 집중식 중재 | 분산식 중재 |
|:---|:---|:---|
| 적용 기준 | 빠른 승인 처리 및 유연한 정책 변경 필요 시 | **단일 장애점** 방지 및 내결함성 확보 필요 시 |
| 핵심 특징 | **중앙 집중식 중재** 제어기 기반 처리 | **분산식 중재** 공유 신호선 논리 합의 |
| 한계 | 중앙 중재기 병목 및 **단일 장애점** 존재 | 신호선 증가 및 **판정 지연** 오버헤드 |

> 요약: 중앙식은 속도, 분산식은 내결함성 우수.

#### 한줄 요약

- 중앙 집중식은 빠른 판정과 정책 변경에 유리하고, 분산식은 단일 장애점을 줄이지만 합의 프로토콜과 판정 지연을 부담한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **고정 우선순위(Fixed Priority)**: 정해진 고정 서열에 따라 버스를 할당하는 정책.
- **라운드 로빈(Round Robin)**: 마스터 간 순서대로 버스 승인 기회를 공평하게 순환 부여하는 정책.
- **기아(Starvation)**: 저우선순위 마스터가 고우선순위 요청에 밀려 지속 전송 불가한 상태.
- **꼬리 지연(Tail Latency)**: 일부 요청의 버스 대기시간이 극단적으로 늘어나는 현상.
- **트래픽 등급(Traffic Class)**: 데이터의 실시간성 및 중요도에 따라 버스 요청을 분류한 등급.
- **예약 대역폭(Reserved Bandwidth)**: 특정 트래픽 등급에 보장된 최소 버스 대역폭.
- **CPU 긴급 요청(CPU Emergency Request)**: 실시간성 보장을 위해 최우선 처리되는 트래픽.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위 구조에서 저순위 요청의 **기아** 발생 | **에이징**·**라운드 로빈** 결합 및 최대 대기 시간 제한 | 모든 마스터 대상 승인 공정성 확보 |
| 특정 마스터의 대량 연속 전송으로 버스 독점 | 최대 **버스트 길이** 및 점유 시간 한도 제한 | 후속 요청의 **꼬리 지연** 완화 |
| 중앙 중재기 장애 발생 시 전체 중재 마비 | 중재기 이중화 및 장애 감지 로직 적용 | **단일 장애점** 방지 및 복구력 향상 |
| 저순위 전송에 밀려 실시간 긴급 트래픽 처리 지연 | **트래픽 등급** 분류 및 **예약 대역폭** 할당 | 긴급 요청에 대한 지연 시간 보장 |

> 사례: **CPU 긴급 요청** 발생 시 최우선 순위 격상 처리

#### 한줄 요약

- 긴급 요청에는 우선순위와 예약 대역폭을 부여하고, 일반 요청에는 버스트 한도와 에이징을 적용해 기아를 제한한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **긴급 요청(Emergency Request)**: 지연 한도 준수를 위해 우선 승인이 필요한 데이터 트래픽.
- **처리 공정성(Processing Fairness)**: 모든 요청 마스터가 유휴 시간 내에 승인 기회를 얻는 특성.
- **중재 정책 선택 기준(Arbitration Selection Criteria)**: 시스템의 실시간성 요구와 공정성을 균형 있게 반영하는 판단 기준.

</details>

- **중재 정책 선택 기준**에 따라 긴급 전송은 **고정 우선순위**, 공정성 요구는 **라운드 로빈·에이징** 적용

#### 한줄 요약

- 긴급 요청은 고정 우선순위로 지연을 제한하고, 일반 요청은 라운드 로빈과 에이징으로 장기 대기와 기아를 방지한다.
