## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 중재(Bus Arbitration)**: 복수의 버스 마스터(CPU, DMA 제어기, GPU 등)가 시스템 공유 버스를 동시에 점유하려 할 때, 전기적 신호 충돌을 방지하고 정해진 우선순위 규칙에 따라 단 하나의 마스터에만 버스 제어권을 위임하는 하드웨어 중재 메커니즘.
- **버스 마스터(Bus Master)**: 시스템 주소 버스와 제어 버스를 주도적으로 구동하여 읽기/쓰기 트랜잭션을 실행할 수 있는 능동 제어 장치.
- **공유 자원 경합(Bus Contention)**: 단일 공통 시스템 버스의 대역폭을 둘 이상의 마스터가 동시에 점유 요청할 때 발생하는 하드웨어 충돌 및 지연 현상.

</details>

- 정의/개념: 다중 **버스 마스터**의 동시 버스 점유 요청 시 우선순위 알고리즘에 따라 제어권을 할당하고 충돌을 방지하는 **버스 중재(Bus Arbitration) 아키텍처**
- 배경/필요성: 단일 공유 버스 환경에서 중재 기제 부재 시 **전기적 신호 충돌, 데이터 파괴 및 특정 저우선순위 마스터의 무한 대기(기아) 발생**

#### 한줄 요약
- 버스 중재는 다중 마스터의 동시 버스 점유 요청을 중재하여 신호 충돌을 방지하고 공정하고 빠른 버스 접근을 보장하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중앙집중식 중재(Centralized Arbitration)**: 시스템 내에 독립된 단일 하드웨어 중재기(Arbiter)가 모든 마스터의 요청을 수신하여 중앙에서 승인을 발행하는 방식.
- **분산식 중재(Distributed Arbitration)**: 각 마스터가 자체 중재 로직을 내장하고 공유 중재 버스를 통해 상호 분산 합의하여 권한을 결정하는 방식.
- **기아 현상(Starvation)**: 고정 우선순위 방식에서 고우선순위 장치의 잦은 요청으로 인해 저우선순위 장치가 버스를 영구히 할당받지 못하는 현상.

</details>

- 제어 주체 분리: 단일 중재기가 통제하는 **중앙집중식 중재**와 각 마스터의 로직이 협력하는 **분산식 중재**로 구분
- 우선순위 스케줄링 다양성: 고정 우선순위(Fixed), 회전 우선순위(Round-Robin), 가중치 공정 큐잉(WFQ) 등을 적용하여 **기아 현상(Starvation)** 방지
- 초저지연 핸드셰이크: **버스 요청(BREQ)** ➔ **버스 승인(BGRT)** ➔ **버스 점유(BBUSY)** 신호 체계를 통해 1~2클록 내에 신속한 버스 제어권 절체 실현

#### 한줄 요약
- 중앙집중식과 분산식 구조로 나뉘며, 라운드로빈 및 가중치 스케줄링을 통해 기아 현상을 방지하고 빠른 핸드셰이크를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **버스 요청선(Bus Request, BREQ)**: 버스 마스터가 중재기에 버스 사용 권한을 요청하는 하드웨어 제어선.
- **버스 승인선(Bus Grant, BGRT)**: 중재기가 특정 마스터에게 버스 점유 권한을 위임했음을 알리는 신호선.
- **버스 점유선(Bus Busy, BBUSY)**: 현재 마스터가 실제 데이터 전송 트랜잭션을 수행 중임을 알리는 공통 신호선.

</details>

```text
[중앙집중식 버스 중재 구조]
 ┌────────────────────── [ 중앙 버스 중재기 (Bus Arbiter) ] ──────────────────────┐
 │  ├─ 요청 판별기 (Priority Resolver: Fixed / Round-Robin / Weighted)           │
 │  └─ 상태 레지스터 (Master Grant Status)                                        │
 └───────┬──────────────────────────┬──────────────────────────┬──────────────────┘
   BREQ0 │ BGRT0              BREQ1 │ BGRT1              BREQN │ BGRTN
         ▼                          ▼                          ▼
 [ 버스 마스터 0 (CPU) ]    [ 버스 마스터 1 (DMAC) ]   [ 버스 마스터 N (GPU/NIC) ]
         │                          │                          │
 ════════╧══════════════════════════╧══════════════════════════╧═════════════════════
                      공통 시스템 버스 (주소/데이터/제어선) + [공통 BBUSY 선]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 마스터는 전용 BREQ/BGRT 선으로 중재기와 통신하고 데이터는 공통 시스템 버스로 전송함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **중앙 버스 중재기** | 메인보드 칩셋 / SoC | 다중 요청 신호 수신 및 우선순위 알고리즘에 따른 **BGRT 승인 발행** | 하드웨어 전용 중재 회로 |
| **버스 요청선 (BREQ)**| 마스터 ➔ 중재기 | 마스터가 버스 제어권을 획득하고자 할 때 활성화 | 마스터별 독립 배선 |
| **버스 승인선 (BGRT)**| 중재기 ➔ 마스터 | 선택된 승인 마스터에게 버스 점유 허가 신호 전달 | 1개 마스터만 High 활성화 |
| **버스 점유선 (BBUSY)**| 공통 버스 공유 라인| 현재 마스터가 데이터 전송 중임을 알리고 타 마스터 진입 차단 | 전송 종료 시 Low 해제 |

#### 한줄 요약
- 버스 중재 시스템은 중앙 중재기, 독립 BREQ/BGRT 신호선, 공통 BBUSY 점유선 및 마스터 내부 인터페이스로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **중재 지연(Arbitration Latency)**: 마스터가 BREQ를 활성화한 시점부터 중재기를 거쳐 BGRT를 받고 실제 전송을 시작하기까지 소요되는 클록 사이클.

</details>

```text
1. 버스 마스터(CPU/DMA)의 데이터 전송 필요 발생 ➔ BREQ 신호 High 인가
                      │
                      ▼
2. 중재기: 현재 공통 BBUSY(Bus Busy) 선이 활성 상태인지 검사
   ┌──────────────────┴──────────────────┐
[ BBUSY=1 (타 마스터 전송 중) ]       [ BBUSY=0 (버스 유휴 상태) ]
   │                                     │
   ▼                                     ▼
중재기 대기열에서 대기                 3. 우선순위 스케줄러(Round-Robin/Fixed) 판정
   │                                     │
   │                                     ▼
   │                              4. 당선된 마스터로 BGRT(Bus Grant) 신호 인가
   │                                     │
   │                                     ▼
   │                              5. 마스터가 BGRT 수신 ➔ BBUSY=1 활성화 ➔ BREQ 해제
   │                                     │
   │                                     ▼
   │                              6. 공통 시스템 버스로 데이터 블록 고속 전송
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 데이터 전송 완료 ➔ BBUSY=0 해제 (다음 대기 마스터 중재 시작)
```

분기 결과: **버스가 비어 있으면** 1클록 내에 BGRT를 받아 즉시 전송을 개시하나, **사용 중이면** 이전 전송 완료(BBUSY=0) 시까지 대기함

#### 한줄 요약
- BREQ 요청 ➔ BBUSY 검사 ➔ 우선순위 판정 ➔ BGRT 승인 ➔ BBUSY 활성화 및 데이터 전송 ➔ 완료 후 버스 반환 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 중재 방식 | 데이지체인 (Daisy Chain) | 독립 요청 방식 (Independent) | 폴링 방식 (Polling) | 분산 중재 (Distributed) |
|:---|:---|:---|:---|:---|
| 우선순위 결정 | **물리적 직렬 배선 순서 (고정)** | **중재기 내부 스케줄링 (가변)** | 중재기 카운터 순회 순서 | **각 마스터 간 식별자 비교** |
| 신호선 수 | **극소 (승인선 1쌍만 직렬 연결)** | 많음 ($2N$개 독립 BREQ/BGRT) | 중간 ($\log_2 N$개 주소선 필요) | 중간 (공유 중재 버스 필요) |
| 중재 속도 | 신호 전파 지연 수반 (중간) | **최고속 (1클록 내 즉시 판정)** | 느림 (폴링 순회 지연 발생) | 빠름 |
| 확장성 및 결함 | **단일 마스터 고장 시 전체 마비** | 우수 (마스터 추가/제거 용이) | 보통 | **매우 우수 (중앙 병목 없음)** |
| 주요 적용처 | 구형 버스, 저비용 임베디드 | **현대 고성능 시스템 버스 (PCIe)** | 특수 산업용 제어기 | 멀티프로세서 공유 패브릭 |

#### 한줄 요약
- 배선 절약에는 데이지체인이 쓰였으나, 현대 고성능 시스템은 초저지연과 정책 유연성을 제공하는 독립 요청 방식(Independent)이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가중치 공정 큐잉(Weighted Fair Queuing, WFQ)**: 각 마스터의 중요도와 대역폭 요구량에 비례하여 버스 점유 타임슬롯을 가중 분배하는 기법.
- **버스 타임아웃(Bus Timeout)**: 특정 마스터가 버스를 점유한 후 일정 시간 이상 해제하지 않을 때 하드웨어가 강제로 BGRT를 회수하는 보호 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위 방식으로 인한 저우선순위 장치 **기아(Starvation)** | **라운드 로빈(Round-Robin) 및 WFQ 가중치 스케줄링** 적용 | 모든 마스터의 최대 대기 지연시간 상한 보장 |
| 마스터 수 증가에 따른 독립 요청 신호선 과다 및 핀 수 부족 | **2단계 계층형 중재기(Hierarchical Arbiter)** 구조 도입 | 핀 수 50% 절감 및 모듈형 확장성 확보 |
| 특정 마스터 오동작으로 인한 무한 버스 점유 및 시스템 교착 | **하드웨어 버스 타임아웃 타이머(Watchdog) 및 강제 선점** | 시스템 중단 차단 및 결함 마스터 격리 |

#### 한줄 요약
- 실무에서는 라운드로빈/WFQ로 기아를 방지하고, 계층형 중재기로 핀 수를 절감하며, 버스 타임아웃으로 결함을 격리한다.

## Ⅶ. 결론

- 다중 마스터 기반 고성능 컴퓨터 시스템의 데이터 전송 효율과 공정성을 보장하기 위해 **초저지연 독립 요청 방식(Independent)과 라운드로빈/WFQ 가중 중재기를 표준 채택**하고, 마스터 수 증가 시 **계층형 분산 중재 아키텍처**를 적용하며, 시스템 결함 방지를 위해 **하드웨어 버스 타임아웃 및 강제 선점 보호 회로**를 필수 구현하는 고신뢰 버스 인터페이스 구축

#### 한줄 요약
- 버스 중재는 충돌 방지와 공정한 자원 분배를 달성하는 핵심 기술이며, 독립 요청 방식과 워치독 보호의 결합으로 완성된다.
