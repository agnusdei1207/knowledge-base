## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **버스 중재**: 여러 요청 중 하나에 공유 버스 사용권을 배타적으로 승인해 충돌을 막는 제어이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 프로그램 명령을 실행하는 장치이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치와 메모리 사이를 직접 전송하는 방식이다.
- **버스 마스터**: 승인 후 버스 트랜잭션을 시작하는 CPU•DMA 등의 주체이다.

</details>

- 정의/개념: 여러 마스터의 동시 요청을 평가해 한 시점에 하나의 공유 버스 사용권만 승인하는 **버스 중재** 기법이다.
- 배경/필요성: 다중 버스 마스터 구조에서 동시 신호 구동이 발생하면 전기적 충돌(Collision)과 데이터 훼손이 일어난다.

#### 한줄 요약

- 버스 중재기는 동시 요청 중 하나의 마스터만 승인해 공유 버스의 신호 충돌을 방지한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **배타적 소유권**: 한 시점에 하나의 마스터만 공유 버스를 구동할 수 있게 하는 권한이다.
- **버스트 길이**: 한 번의 승인으로 연속 처리할 수 있는 전송량이다.
- **에이징**: 오래 기다린 요청의 우선순위를 높여 기아를 방지하는 기법이다.
- **우선순위**: 여러 요청 가운데 먼저 승인할 대상을 정하는 서열이다.
- **버스트 한도**: 한 번의 승인으로 연속 처리할 수 있는 버스트 길이의 최대값이다.

</details>

- 다중 마스터의 동시 구동을 차단하는 **배타적 소유권**이 핵심이다.
- **우선순위•버스트 한도** 설정에 따라 달라지는 대기시간이 핵심이다.
- 저우선순위 요청의 기아를 막는 **에이징**이 핵심이다.

#### 한줄 요약

- 우선순위와 버스트 한도는 긴급 요청의 지연을 제한하고, 에이징은 오래 기다린 저순위 요청의 기아를 방지한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **요청 신호**: 마스터가 버스 사용 의사를 알리는 신호이다.
- **승인 신호**: 중재기가 마스터에 배타적 권한을 부여하는 신호이다.
- **중재기**: 요청을 정책에 따라 평가해 하나의 승인 대상을 선택하는 제어기이다.
- **공유 버스**: 승인받은 마스터의 주소•제어•데이터를 대상 장치에 전달하는 공용 경로이다.

</details>

```text
[버스 마스터 집합] ----- [중재기] ----- [공유 버스]
```

선의 의미: 선은 요청•승인 신호와 배타적 버스 사용권을 공유하는 인접 구성요소의 정적 중재 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 버스 마스터 집합 | 사용권 요청•승인 후 전송 |
| 중재기 | 정책 기반 단일 승인 대상 선택 |
| 공유 버스 | 승인 마스터의 배타적 경로 제공 |

#### 한줄 요약

- 여러 마스터가 요청하면 중재기가 하나만 승인해 공유 버스의 충돌을 막는다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **경합 상태**: 둘 이상의 마스터가 같은 시점에 버스 사용권을 요청한 상태이다.
- **시간 할당량**: 한 마스터가 연속 점유할 수 있는 최대 전송 시간이나 버스트 수이다.
- **사용권 반납**: 전송 종료 후 버스 점유를 해제해 다음 대기자 승인을 가능하게 하는 동작이다.
- **요청 상태 수집**: 각 버스 마스터의 요청 유무와 누적 대기 시간을 확인하는 단계이다.
- **정책 판정·단일 승인**: 중재 정책으로 하나의 버스 마스터를 고르는 단계이다.
- **배타적 버스 전송**: 승인된 마스터만 버스트 한도나 시간 할당량 동안 버스를 구동하는 단계이다.
- **다음 마스터 승인**: 남은 요청을 다시 평가해 후속 버스 소유자를 고르는 단계이다.

</details>

```text
                  [CPU•DMA 동시 요청]
                            |
                    1. 요청 상태 수집
                            |
               2. 정책 판정•단일 마스터 승인
                    /               \
               [승인 마스터]       [비승인 대기]
                    |                    |
      +-----------------------------+    |
      | 반복: 허용 버스트•할당량   |    |
      | 3. 승인 마스터 버스 전송    |    |
      +-----------------------------+    |
                    |                    |
                 4. 사용권 반납          |
                    |                    |
                    +---------+----------+
                              |
                     5. 다음 마스터 승인
                              |
                         [전송 순환]
```

### 동작 원리

1. **요청 상태 수집**: CPU·DMA 등 마스터의 **요청 신호**를 모아 경합 상태와 누적 대기 시간을 확인한다.
2. **정책 판정·단일 승인**: 고정 우선순위·라운드 로빈·에이징 정책으로 하나의 마스터를 선택한다.
3. **배타적 버스 전송**: 승인한 마스터만 허용된 버스트 길이 또는 시간 할당량 동안 버스를 구동한다.
4. **사용권 반납**: 전송 완료나 할당량 소진 시 현재 마스터의 버스 점유를 해제한다.
5. **다음 마스터 승인**: 남은 대기 요청을 다시 평가해 후속 소유자를 선택하고 전송을 순환한다.

#### 한줄 요약

- 중재기는 동시 요청 중 하나만 승인하고, 버스트 한도가 끝나면 사용권을 회수해 다음 대기 요청을 다시 평가한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **중앙 집중식 중재**: 하나의 중재기가 모든 요청을 모아 빠르게 승인 대상을 정하는 방식이다.
- **분산식 중재**: 각 마스터가 공통 규칙과 신호로 승인 대상을 함께 결정하는 방식이다.
- **단일 장애점**: 하나의 구성요소 고장만으로 전체 버스 중재가 중단되는 지점이다.
- **판정 지연**: 요청이 발생한 뒤 중재 결과와 승인 신호를 받기까지 걸리는 시간이다.

</details>

| 버스 중재 방식 | 중앙 집중식 중재 | 분산식 중재 |
|:---|:---|:---|
| 적용 기준 | 빠른 승인과 유연한 우선순위 정책이 필요할 때 | 중앙 중재기의 **단일 장애점**을 피할 때 |
| 핵심 특징 | **중앙 집중식 중재** | **분산식 중재** |
| 한계 | 중재기 병목•**단일 장애점** | 프로토콜 복잡도•**판정 지연** |

> 요약: 중앙식은 속도, 분산식은 장애 분산이 핵심이다.

#### 한줄 요약

- 중앙 집중식은 빠른 판정과 정책 변경에 유리하고, 분산식은 단일 장애점을 줄이지만 합의 프로토콜과 판정 지연을 부담한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **고정 우선순위**: 정해진 서열로 버스 요청을 고르는 정책이다.
- **라운드 로빈**: 승인 기회를 마스터 순서대로 순환하는 정책이다.
- **기아**: 낮은 순위 요청이 계속 처리되지 않는 문제이다.
- **꼬리 지연**: 일부 요청의 대기시간이 크게 늘어나는 문제이다.
- **트래픽 등급**: 긴급도에 따라 버스 요청을 분류한 값이다.
- **예약 대역폭**: 특정 트래픽 등급에 보장하는 최소 전송량이다.
- **CPU 긴급 요청**: 지연 한도를 위해 우선 승인이 필요한 CPU 트래픽이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위 요청이 계속 도착해 **기아** 발생 | **에이징·라운드 로빈**과 요청별 최대 대기 시간 감시 | 모든 마스터의 승인 기회 확보 |
| 한 마스터의 긴 버스트가 공유 버스를 계속 독점 | 최대 **버스트 길이·시간 할당량** 제한 | 후속 요청의 **꼬리 지연** 완화 |
| 모든 요청이 중앙 중재기에 몰려 판정 병목과 **단일 장애점** 발생 | 중재기 이중화·계층화와 오류 검출 적용 | 중재 부하와 장애 범위 분산 |
| 저순위 장기 전송 때문에 긴급 요청이 늦어 실시간 지연 상한 초과 | **트래픽 등급·예약 대역폭** 설정 후 최악 지연 검증 | 긴급 요청의 서비스 기회 확보 |

> 사례: 고정 우선순위를 부여하는 **CPU 긴급 요청**

#### 한줄 요약

- 긴급 요청에는 우선순위와 예약 대역폭을 부여하고, 일반 요청에는 버스트 한도와 에이징을 적용해 기아를 제한한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **긴급 요청**: 최악 지연 한도를 지키기 위해 다른 트래픽보다 먼저 승인해야 하는 요청이다.
- **처리 공정성**: 모든 마스터가 제한된 대기시간 안에 버스 사용 기회를 얻는 성질이다.
- **중재 정책 선택 기준**: 요청 긴급도와 처리 공정성으로 우선순위·라운드 로빈·에이징을 고르는 기준이다.

</details>

- **중재 정책 선택 기준**에 따라 **긴급 요청**에는 **고정 우선순위**, **처리 공정성**에는 **라운드 로빈·에이징**을 적용한다.

#### 한줄 요약

- 긴급 요청은 고정 우선순위로 지연을 제한하고, 일반 요청은 라운드 로빈과 에이징으로 장기 대기와 기아를 방지한다.
