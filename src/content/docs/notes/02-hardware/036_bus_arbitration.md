## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 중재(Bus Arbitration)**: 복수의 버스 마스터(CPU, DMA 제어기, GPU 등)가 시스템 공유 버스를 동시에 점유하려 할 때, 전기적 신호 충돌을 방지하고 정해진 우선순위 규칙에 따라 단 하나의 마스터에만 버스 제어권을 위임하는 하드웨어 중재 메커니즘.
- **버스 마스터(Bus Master)**: 시스템 주소 버스와 제어 버스를 주도적으로 구동하여 읽기/쓰기 트랜잭션을 실행할 수 있는 능동 제어 장치.
- **공유 자원 경합(Bus Contention)**: 단일 공통 시스템 버스의 대역폭을 둘 이상의 마스터가 동시에 점유 요청할 때 발생하는 하드웨어 충돌 및 지연 현상.

</details>

- 정의/개념: 복수의 버스 마스터가 공유 시스템 버스를 동시 점유하려 할 때 신호 충돌을 방지하고 우선순위에 따라 단일 마스터에 권한을 위임하는 **하드웨어 제어 체계**
- 배경/필요성: 단일 공유 버스 환경에서 복수 마스터의 동시 구동에 따른 전기적 신호 충돌(Contention) 방지 및 특정 장치 독점에 의한 기아 현상 차단

#### 한줄 요약
- 버스 중재는 다중 마스터의 동시 버스 점유 요청을 중재하여 신호 충돌을 방지하고 공정하고 빠른 버스 접근을 보장하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중앙집중식 중재(Centralized Arbitration)**: 시스템 내에 독립된 단일 하드웨어 중재기(Arbiter)가 모든 마스터의 요청을 수신하여 중앙에서 승인을 발행하는 방식.
- **분산식 중재(Distributed Arbitration)**: 각 마스터가 자체 중재 로직을 내장하고 공유 중재 버스를 통해 상호 분산 합의하여 권한을 결정하는 방식.
- **기아 현상(Starvation)**: 고정 우선순위 방식에서 고우선순위 장치의 잦은 요청으로 인해 저우선순위 장치가 버스를 영구히 할당받지 못하는 현상.

</details>

- 단일 중재기가 전권을 행사하는 **중앙집중식 중재**와 마스터 간 분산 합의하는 **분산식 중재** 구조로 이원화
- **고정 우선순위, 라운드로빈, WFQ** 등의 스케줄링 기법을 적용하여 지연 시간 단축과 기아 현상 방지 절충
- **버스 요청(BREQ), 버스 승인(BGRT), 버스 점유(BBUSY)** 신호선 핸드셰이크를 통해 초저지연 버스 권한 절체 실현

#### 한줄 요약
- 중앙집중식과 분산식 구조로 나뉘며, 라운드로빈 및 가중치 스케줄링을 통해 기아 현상을 방지하고 빠른 핸드셰이크를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **버스 요청선(Bus Request, BREQ)**: 버스 마스터가 중재기에 버스 사용 권한을 요청하는 하드웨어 제어선.
- **버스 승인선(Bus Grant, BGRT)**: 중재기가 특정 마스터에게 버스 점유 권한을 위임했음을 알리는 신호선.
- **버스 점유선(Bus Busy, BBUSY)**: 현재 마스터가 실제 데이터 전송 트랜잭션을 수행 중임을 알리는 공통 신호선.

</details>

```text
[버스 중재 서브시스템]
  │
  ├─ [다중 버스 마스터군] (CPU / DMAC / GPU 장치)
  │     ├─ [독립 버스 요청선] (BREQ, 마스터별 전용 요청)
  │     ├─ [독립 버스 승인선] (BGRT, 마스터별 권한 인가)
  │     └─ [공통 버스 점유선] (BBUSY, 버스 사용 상태 공유)
  │
  ├─ [중앙 집중식 버스 중재기] (Bus Arbiter ASIC)
  │     ├─ [요청 판별 및 래치] (BREQ 다중 신호 동시 수신)
  │     ├─ [우선순위 스케줄러] (라운드로빈 / WFQ 공정 배분)
  │     └─ [타임아웃 감시 로직] (무한 점유 방지 및 강제 회수)
  │
  └─ [시스템 공유 버스] (공통 주소·데이터·제어 신호선)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 중앙 버스 중재기 | 다중 요청 수신 시 우선순위 알고리즘을 수행하여 **단일 승인(BGRT) 인가** |
| 버스 요청선 (BREQ) | 각 마스터가 중재기에 버스 사용 희망을 알리는 **독립 신호선** |
| 버스 승인선 (BGRT) | 당선된 특정 마스터에게 버스 점유 권한을 위임하는 **허가 신호선** |
| 버스 점유선 (BBUSY) | 현재 마스터가 실제 트랜잭션을 수행 중임을 알리는 **공통 상태선** |

#### 한줄 요약
- 점유권 판단이 중앙 중재기 한 곳으로 모이는 대신 마스터마다 BREQ·BGRT 전용 선을 따로 깔아야 하고, 지금 버스가 쓰이는지는 BBUSY 한 가닥이 모든 마스터에 공통으로 알려 마스터별 확인 절차를 없앤다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **중재 지연(Arbitration Latency)**: 마스터가 BREQ를 활성화한 시점부터 중재기를 거쳐 BGRT를 받고 실제 전송을 시작하기까지 소요되는 클록 사이클.

</details>

```text
+-------------------------------------------------------------+
|               버스 마스터의 전송 요청 발생 (BREQ=1)          |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     1. 버스 점유 상태 검사    |
               +-------------------------------+
                      |                 |
             [BBUSY=1 (사용 중)]        | [BBUSY=0 (유휴 상태)]
                      |                 v
                      | +-------------------------------+
                      | | 2. 우선순위 스케줄링 알고리즘 |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 3. 당선 마스터로 BGRT 승인    |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 4. BBUSY 활성화 및 데이터 전송|
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 중재기 대기열 큐잉    |               |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                                v
+-------------------------------------------------------------+
|       5. 전송 완료 후 BBUSY 해제 및 버스 제어권 반납         |
+-------------------------------------------------------------+
```

분기 결과: 버스가 **유휴 상태(BBUSY=0)**이면 우선순위 판정 후 즉시 BGRT가 인가되어 1사이클 내 전송을 개시하나, **사용 중(BBUSY=1)**이면 현재 트랜잭션 종료 시까지 대기 큐에서 지연됨

**동작 원리**

1. **버스 상태 검사 및 요청 수신**: 특정 마스터가 자신의 독립 BREQ 선을 하이(High)로 인가하면 중재기가 공통 BBUSY 선의 활성화 여부 감시
2. **우선순위 스케줄링 연산**: 복수 마스터의 동시 요청 발생 시 라운드로빈 또는 고정 우선순위 로직에 따라 이번 사이클에 권한을 획득할 단일 마스터 결정
3. **버스 승인 신호(BGRT) 인가**: 중재기가 선정된 마스터로 연결된 전용 BGRT 라인만 활성화하여 버스 사용 허가 통지
4. **버스 점유(BBUSY) 활성화 및 전송**: 승인을 확인한 마스터가 공통 BBUSY 신호를 구동하여 타 마스터의 침범을 차단하고 주소/데이터 버스로 트랜잭션 실행
5. **버스 해제 및 제어권 반납**: 데이터 전송이 완료된 마스터가 BREQ와 BBUSY 신호를 비활성화하여 버스를 즉시 유휴 상태로 전환

#### 한줄 요약
- 버스가 유휴일 때조차 점유 검사와 우선순위 판정에 해당하는 중재 지연을 요청마다 치르는 대신, 복수 마스터가 동시에 버스를 구동해 생기는 충돌 자체를 없앤다.

## Ⅴ. 종류 및 비교

| 버스 중재 방식 | 데이지체인 (Daisy Chain) | 독립 요청 방식 (Independent) | 폴링 방식 (Polling) | 분산 중재 (Distributed) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 신호선 최소화 및 저비용 직렬 임베디드 버스 | 초고속 판정 및 유연한 동적 우선순위 요구 시스템 | 장치 동적 추가가 빈번하고 유연한 순회 우선순위 요구 시 | 중앙 중재기 병목을 제거해야 하는 멀티프로세서 패브릭 |
| 핵심 특징 | 직렬 승인선 1쌍 기반 **물리 배선 순서로 우선순위 자동 결정** | 마스터별 1:1 독립 배선 및 **중앙 스케줄링(RR/WFQ) 제어** | 중재기가 **지정 주소를 순회 송출**하여 일치 장치에 위임 | 공유 중재 버스 상에서 **마스터 고유 ID 비교**로 자체 선점 |
| 한계 | 체인 후순위 전파 지연 및 **앞단 장치 고장 시 전체 마비** | 마스터 수 비례 $2N$개 배선 필요에 따른 **핀 수 및 회로 증가** | 폴링 카운터 순회에 따른 **중재 지연 및 주소선 추가** | 각 마스터마다 **중재 비교 로직 내장 필요 및 복잡도 증가** |

#### 한줄 요약
- 배선 절약에는 데이지체인이 쓰였으나, 현대 고성능 시스템은 초저지연과 정책 유연성을 제공하는 독립 요청 방식(Independent)이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가중치 공정 큐잉(Weighted Fair Queuing, WFQ)**: 각 마스터의 중요도와 대역폭 요구량에 비례하여 버스 점유 타임슬롯을 가중 분배하는 기법.
- **버스 타임아웃(Bus Timeout)**: 특정 마스터가 버스를 점유한 후 일정 시간 이상 해제하지 않을 때 하드웨어가 강제로 BGRT를 회수하는 보호 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위 적용 시 저순위 마스터의 무한 기아 | **라운드로빈** 및 **WFQ 가중치 스케줄링** 적용 | 모든 마스터의 최대 대기 시간 상한 보장 |
| 마스터 수 증가에 따른 독립 요청 배선 과다 및 핀 부족 | **2단계 계층형 중재기(Hierarchical Arbiter)** 구축 | 핀 수 대폭 절감 및 모듈형 서브 버스 확장 |
| 마스터 하드웨어 이상으로 버스를 독점하여 시스템 교착 발생 | 하드웨어 **버스 타임아웃 타이머** 및 강제 선점 회로 | 시스템 정지 방지 및 고장 마스터 격리 |

#### 한줄 요약
- 실무에서는 라운드로빈/WFQ로 기아를 방지하고, 계층형 중재기로 핀 수를 절감하며, 버스 타임아웃으로 결함을 격리한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **크로스바 스위치(Crossbar Switch)**: 단일 공유 버스 대신 $N \times M$ 격자형 스위칭 패브릭을 구성하여 비경합 포트 간 동시 병렬 전송을 실현하는 고성능 인터커넥트 구조.
- **네트워크 온 칩(Network-on-Chip, NoC)**: SoC 내부의 수많은 IP 코어 간 버스 경합을 해결하기 위해 패킷 스위칭 라우터 네트워크를 칩 내부에 집적한 아키텍처.

</details>

다중 마스터 환경에서 신호 충돌을 원천 차단하고 공정성을 보장하는 핵심 중재 메커니즘이며, 향후 크로스바 스위치 및 네트워크 온 칩(NoC) 패킷 라우팅과의 결합을 통한 대역폭 확장.

#### 한줄 요약
- 버스 중재는 충돌 방지와 공정한 자원 분배를 달성하는 핵심 기술이며, 독립 요청 방식과 워치독 보호의 결합으로 완성된다.
