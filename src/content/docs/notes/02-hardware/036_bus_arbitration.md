## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **버스 중재**: 여러 요청 중 하나에 공유 버스 사용권을 배타적으로 승인해 충돌을 막는 제어
- **버스 마스터**: 사용권을 요청하고 승인 후 버스 트랜잭션을 시작하는 중앙 처리 장치(Central Processing Unit, CPU)·직접 메모리 접근(Direct Memory Access, DMA) 엔진 등의 주체

</details>

- 정의/개념: 동시 요청 중 공유 버스 **사용권을 하나에 배정하는 기법**
- 배경/필요성: 동시 요청의 **버스 경합·신호 충돌** 방지

#### 한줄 요약

- 여러 사람이 마이크를 요청하면 사회자가 한 명에게만 발언권을 준다

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **배타적 소유권**: 한 시점에 하나의 마스터만 공유 버스를 구동할 수 있게 하는 권한
- **버스트 길이**: 한 번의 승인으로 연속 처리할 수 있는 전송량
- **에이징**: 오래 기다린 요청의 우선순위를 높여 기아를 방지하는 기법

</details>

- 다중 마스터의 동시 구동을 차단하는 **배타적 소유권**
- **우선순위·버스트 한도** 설정에 따라 달라지는 대기시간
- 저우선순위 요청의 기아를 막는 **에이징**

#### 한줄 요약

- 급한 사람을 먼저 부르되 오래 기다린 사람의 차례도 보장한다

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **요청·승인 신호**: 마스터의 버스 사용 의사와 중재기가 부여한 배타적 권한을 나타내는 신호
- **중재기**: 요청을 정책에 따라 평가해 하나의 승인 대상을 선택하는 제어기
- **공유 버스**: 승인받은 마스터의 주소·제어·데이터를 대상 장치에 전달하는 공용 경로

</details>

```mermaid
block
    columns 3
    M["버스 마스터 집합"]
    A["중재기"]
    B["공유 버스"]
    M --- A
    A --- B
```

| 구성요소 | 책임 |
|:---|:---|
| 버스 마스터 집합 | 사용권 요청·**승인 후 전송** |
| 중재기 | 정책 기반 **단일 승인 대상** 선택 |
| 공유 버스 | 승인 마스터의 **배타적 경로** 제공 |

#### 한줄 요약

- 여러 마스터가 요청하면 중재기가 하나만 승인해 공유 버스의 충돌을 막는다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **경합 상태**: 둘 이상의 마스터가 같은 시점에 버스 사용권을 요청한 상태
- **시간 할당량**: 한 마스터가 연속 점유할 수 있는 최대 전송 시간이나 버스트 수
- **사용권 반납**: 전송 종료 후 버스 점유를 해제해 다음 대기자 승인을 가능하게 하는 동작
- **중앙 처리 장치(Central Processing Unit, CPU)·직접 메모리 접근(Direct Memory Access, DMA) 마스터**: 동시에 버스 사용권을 요청할 수 있는 프로세서와 전용 전송 엔진

</details>

```mermaid
sequenceDiagram
    participant C as CPU 마스터
    participant D as DMA 마스터
    participant A as 중재기
    participant B as 공유 버스
    participant T as 대상 메모리·장치
    par 동시 사용권 요청
        C->>A: 1. 동시 사용권 요청
    and
        D->>A: 동시 사용권 요청
    end
    A-->>C: 2. 단일 마스터 승인
    A-->>D: 비승인 대기 유지
    C->>B: 3. 주소·제어 신호
    B->>T: 대상 전송 요청
    loop 허용된 버스트 길이
        T-->>B: 데이터·응답 전달
        B-->>C: 버스트 데이터 반환
    end
    C->>A: 4. 사용권 반납
    A-->>D: 5. 다음 마스터 승인
```

**동작 원리**

1. **동시 사용권 요청**: CPU·DMA의 경합 상태 형성
2. **단일 마스터 승인**: 우선순위·공정성 정책으로 선택
3. **주소·제어 신호**: 승인 주체만 버스 트랜잭션 구동
4. **사용권 반납**: 버스트 종료 후 점유 해제
5. **다음 마스터 승인**: 대기 요청 중 후속 소유자 선택

#### 한줄 요약

- 중재기는 동시 요청 중 하나만 승인하고 버스트가 끝나면 다음 대기자에게 사용권을 넘긴다

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **중앙 집중식 중재**: 하나의 중재기가 모든 요청을 모아 빠르게 승인 대상을 정하는 방식
- **분산식 중재**: 각 마스터가 공통 규칙과 신호로 승인 대상을 함께 결정하는 방식
- **단일 장애점**: 하나의 구성요소 고장만으로 전체 버스 중재가 중단되는 지점

</details>

| 버스 중재 방식 | 중앙 집중식 중재 | 분산식 중재 |
|:---|:---|:---|
| 적용 기준 | 빠른 판정·**유연한 정책** | 단일 장애점 제거·**확장성** |
| 핵심 특징 | 중재기의 **요청·승인 판정** | 마스터의 **분산 규칙 공동 판정** |
| 한계 | 중재기 병목·**단일 장애점** | 프로토콜 복잡도·**판정 지연** |

> 요약: 중앙식은 속도, 분산식은 장애 분산

#### 한줄 요약

- 사회자 한 명은 빠르고, 공동 판정은 고장점이 적지만 복잡하다

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **고정 우선순위·라운드 로빈**: 정해진 서열로 요청을 고르거나 승인 기회를 순서대로 순환하는 정책
- **기아·꼬리 지연**: 낮은 순위 요청이 계속 처리되지 않거나 일부 요청의 대기시간이 크게 늘어나는 문제
- **트래픽 등급·예약 대역폭**: 긴급도별 요청 분류와 특정 등급에 보장하는 최소 전송량
- **시스템 온 칩(System on Chip, SoC)**: 프로세서·메모리 제어기·주변장치를 한 칩에 통합하고 내부 인터커넥트를 공유하는 반도체
- **중앙 처리 장치(Central Processing Unit, CPU) 긴급 요청**: 실시간·지연 민감 처리를 위해 우선 승인이 필요한 프로세서 트래픽

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위로 저순위 요청 기아 | **에이징·라운드 로빈**과 최대 대기 시간 감시 | **처리 공정성** 확보 |
| 긴 버스트가 버스를 계속 독점 | 최대 **버스트 길이·시간 할당량** 제한 | **꼬리 지연** 완화 |
| 중앙 중재기 병목·단일 장애 | **이중화·계층형 중재**와 오류 검출 적용 | **가용성·확장성** 향상 |
| 긴급 요청의 우선순위 역전·지연 상한 초과 | **트래픽 등급·예약 대역폭**과 최악 지연 검증 | **실시간 요구** 보장 |

> 사례: 고정 우선순위를 부여하는 **CPU 긴급 요청**

#### 한줄 요약

- SoC 인터커넥트는 CPU 긴급 요청을 우선 승인하되 최대 버스트 길이와 에이징으로 다른 마스터의 꼬리 지연과 기아를 제한한다

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **긴급 요청**: 최악 지연 한도를 지키기 위해 다른 트래픽보다 먼저 승인해야 하는 요청
- **처리 공정성**: 모든 마스터가 제한된 대기시간 안에 버스 사용 기회를 얻는 성질

</details>

- 긴급은 **고정 우선순위**, 공정성은 **라운드 로빈·에이징** 적용

#### 한줄 요약

- 급한 요청을 먼저 보내되 오래 기다린 요청의 차례도 지킨다
