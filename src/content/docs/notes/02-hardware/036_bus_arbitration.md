## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **버스 중재**: 여러 요청 중 하나에 공유 버스 사용권을 배타적으로 승인해 충돌을 막는 제어
- **중앙 처리 장치(Central Processing Unit, CPU)**: 프로그램 명령을 실행하는 장치
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치와 메모리 사이를 직접 전송하는 방식
- **버스 마스터**: 승인 후 버스 트랜잭션을 시작하는 CPU•DMA 등의 주체

</details>

- 정의/개념: 동시 요청 중 공유 버스 **사용권을 하나에 배정하는 기법**
- 배경/필요성: 동시 요청의 **버스 경합•신호 충돌** 방지

#### 한줄 요약

- 동시 요청에서 **단일 버스 소유권** 을 배타 배정

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **배타적 소유권**: 한 시점에 하나의 마스터만 공유 버스를 구동할 수 있게 하는 권한
- **버스트 길이**: 한 번의 승인으로 연속 처리할 수 있는 전송량
- **에이징**: 오래 기다린 요청의 우선순위를 높여 기아를 방지하는 기법

</details>

- 다중 마스터의 동시 구동을 차단하는 **배타적 소유권**
- **우선순위•버스트 한도** 설정에 따라 달라지는 대기시간
- 저우선순위 요청의 기아를 막는 **에이징**

#### 한줄 요약

- 우선순위•버스트 한도와 **에이징** 으로 지연•기아 조정

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **요청 신호**: 마스터가 버스 사용 의사를 알리는 신호
- **승인 신호**: 중재기가 마스터에 배타적 권한을 부여하는 신호
- **중재기**: 요청을 정책에 따라 평가해 하나의 승인 대상을 선택하는 제어기
- **공유 버스**: 승인받은 마스터의 주소•제어•데이터를 대상 장치에 전달하는 공용 경로

</details>

```text
[버스 마스터 집합] ----- [중재기] ----- [공유 버스]
```

선의 의미: 선은 요청•승인 신호와 배타적 버스 사용권을 공유하는 인접 구성요소의 정적 중재 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 버스 마스터 집합 | 사용권 요청•**승인 후 전송** |
| 중재기 | 정책 기반 **단일 승인 대상** 선택 |
| 공유 버스 | 승인 마스터의 **배타적 경로** 제공 |

#### 한줄 요약

- 여러 마스터가 요청하면 중재기가 하나만 승인해 공유 버스의 충돌을 막는다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **경합 상태**: 둘 이상의 마스터가 같은 시점에 버스 사용권을 요청한 상태
- **시간 할당량**: 한 마스터가 연속 점유할 수 있는 최대 전송 시간이나 버스트 수
- **사용권 반납**: 전송 종료 후 버스 점유를 해제해 다음 대기자 승인을 가능하게 하는 동작

</details>

```text
                  [CPU•DMA 동시 요청]
                            |
                    1. 요청 상태 수집
                            |
               2. 정책 판정•단일 마스터 승인
                    /               \
               [승인 마스터]       [비승인 대기]
                    |                    |
      +-----------------------------+    |
      | 반복: 허용 버스트•할당량   |    |
      | 3. 승인 마스터 버스 전송    |    |
      +-----------------------------+    |
                    |                    |
                 4. 사용권 반납          |
                    |                    |
                    +---------+----------+
                              |
                     5. 다음 마스터 승인
                              |
                         [전송 순환]
```

**동작 원리**

- **1. 요청 상태 수집**: CPU•DMA의 경합과 대기시간 확인
- **2. 정책 판정•단일 마스터 승인**: 우선순위•공정성 적용
- **3. 승인 마스터 버스 전송**: 허용 버스트만 배타 구동
- **4. 사용권 반납**: 버스트 종료 후 점유 해제
- **5. 다음 마스터 승인**: 대기 요청에서 후속 소유자 선택

#### 한줄 요약

- 중재기는 동시 요청 중 하나만 승인하고 버스트가 끝나면 다음 대기자에게 사용권을 넘긴다

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **중앙 집중식 중재**: 하나의 중재기가 모든 요청을 모아 빠르게 승인 대상을 정하는 방식
- **분산식 중재**: 각 마스터가 공통 규칙과 신호로 승인 대상을 함께 결정하는 방식
- **단일 장애점**: 하나의 구성요소 고장만으로 전체 버스 중재가 중단되는 지점

</details>

| 버스 중재 방식 | 중앙 집중식 중재 | 분산식 중재 |
|:---|:---|:---|
| 적용 기준 | 빠른 판정•**유연한 정책** | 단일 장애점 제거•**확장성** |
| 핵심 특징 | 중재기의 **요청•승인 판정** | 마스터의 **분산 규칙 공동 판정** |
| 한계 | 중재기 병목•**단일 장애점** | 프로토콜 복잡도•**판정 지연** |

> 요약: 중앙식은 속도, 분산식은 장애 분산

#### 한줄 요약

- 중앙식은 **판정 속도**, 분산식은 장애 분산•확장성

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **고정 우선순위**: 정해진 서열로 버스 요청을 고르는 정책
- **라운드 로빈**: 승인 기회를 마스터 순서대로 순환하는 정책
- **기아**: 낮은 순위 요청이 계속 처리되지 않는 문제
- **꼬리 지연**: 일부 요청의 대기시간이 크게 늘어나는 문제
- **트래픽 등급**: 긴급도에 따라 버스 요청을 분류한 값
- **예약 대역폭**: 특정 트래픽 등급에 보장하는 최소 전송량
- **시스템 온 칩(System on Chip, SoC)**: 프로세서•메모리•주변장치를 통합한 반도체
- **CPU 긴급 요청**: 지연 한도를 위해 우선 승인이 필요한 CPU 트래픽

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고정 우선순위로 저순위 요청 기아 | **에이징•라운드 로빈** 과 최대 대기 시간 감시 | **처리 공정성** 확보 |
| 긴 버스트가 버스를 계속 독점 | 최대 **버스트 길이•시간 할당량** 제한 | **꼬리 지연** 완화 |
| 중앙 중재기 병목•단일 장애 | **이중화•계층형 중재** 와 오류 검출 적용 | **가용성•확장성** 향상 |
| 긴급 요청의 우선순위 역전•지연 상한 초과 | **트래픽 등급•예약 대역폭** 과 최악 지연 검증 | **실시간 요구** 보장 |

> 사례: 고정 우선순위를 부여하는 **CPU 긴급 요청**

#### 한줄 요약

- 긴급 우선 후 **버스트 한도•에이징** 으로 기아 제한

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **긴급 요청**: 최악 지연 한도를 지키기 위해 다른 트래픽보다 먼저 승인해야 하는 요청
- **처리 공정성**: 모든 마스터가 제한된 대기시간 안에 버스 사용 기회를 얻는 성질

</details>

- 긴급은 **고정 우선순위**, 공정성은 **라운드 로빈•에이징** 적용

#### 한줄 요약

- 긴급도는 우선순위, 장기 대기는 **에이징** 적용
