## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PUF(Physical Unclonable Function)**: 반도체 제조 공정의 불가피한 미세 물리적 편차를 활용해 칩마다 고유한 무작위 난수 비트를 출력하는 하드웨어 지문 소자.
- **온디맨드 키 생성(Key Generation On-Demand)**: 암호 키를 불휘발성 메모리(NVM)에 영구 저장하지 않고, 필요할 때만 PUF 회로에서 즉석 생성해 사용 후 파기하는 방식.

</details>

- 정의/개념: 제조 공정의 미세 편차에서 칩마다 다른 응답을 끌어내 식별값이나 키 재료로 쓰는 **PUF(Physical Unclonable Function)**
- 배경/필요성: 키를 메모리에 적어 두는 순간 물리적 프로빙과 역공학의 대상이 되므로, 저장하지 않는 **온디맨드 키 생성(Key Generation On-Demand)** 방식이 요구됨

#### 한줄 요약
- 이 기술이 지키는 것은 키의 비밀이 아니라 키의 부재이며, 훔칠 대상이 존재하지 않는다는 점이 다른 어떤 방어보다 강하다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **고유성(Uniqueness)**: 동일한 마스크로 제조된 서로 다른 칩들 간의 PUF 출력 비트가 통계적으로 50%의 해밍 거리를 가지며 서로 완벽히 구분되는 특성.
- **신뢰성(Reliability)**: 동일한 칩에서 온도, 전압, 경년 변화 등 외부 환경이 바뀌어도 항상 동일한 기준 키를 재현해내는 안정성.

</details>

- 같은 응답 특성을 실용적 비용으로 복제하기 어렵다는 물리적 성질
- 전원이 꺼지면 흔적이 남지 않아 정지 상태의 장치에서 탈취할 대상이 없음
- **고유성(Uniqueness)**은 칩 구분을, **신뢰성(Reliability)**은 같은 칩의 재현을 각각 책임지는 상충 지표

#### 한줄 요약
- 칩끼리 충분히 달라야 하면서 같은 칩은 언제나 같아야 한다는 두 요구가 정면으로 충돌하므로, 이 기술의 난도는 회로가 아니라 그 균형점에 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **퍼지 추출기(Fuzzy Extractor)**: 노이즈가 섞인 PUF 원시 응답(Raw Response)에서 BCH/리드솔로몬 에러 정정 부호와 헬퍼 데이터를 이용해 순수 암호키를 추출하는 모듈.
- **헬퍼 데이터(Helper Data)**: 키 등록(Enrollment) 시 생성되어 외부에 공개 저장되는 비민감 보조 데이터로, 키 재현 시 에러 비트 보정에 사용.

</details>

```text
[PUF 키 생성 경로]
├─ PUF 코어 회로 (SRAM 셀·링 발진기)
│  └─ 노이즈 섞인 원시 응답 출력
├─ 퍼지 추출기
│  ├─ 에러 정정 디코더
│  └─ 헬퍼 데이터 (공개 저장·보정용 보조 정보)
├─ 해시·키 유도 함수 (편향 제거 후 균등 엔트로피 확보)
└─ 암호 엔진 (생성 키를 메모리 노출 없이 직결 사용)
```

선의 의미: 가지(`├─`)는 처리 순서이며, 헬퍼 데이터만이 외부에 공개 저장되고 나머지 값은 칩 밖으로 나가지 않음

| 구성요소 | 책임 |
|:---|:---|
| PUF 코어 | 소자 간 미세 편차를 무작위 비트열로 출력 |
| 등록 엔진 | 출하 시 기준 응답을 측정해 **헬퍼 데이터(Helper Data)** 생성 |
| **퍼지 추출기(Fuzzy Extractor)** | 환경 변화로 뒤집힌 비트를 보조 정보로 복원 |
| 해시·키 유도 함수 | 편향된 비트열을 압축해 균등한 키로 변환 |
| 암호 엔진 | 생성된 키를 메모리 경유 없이 직접 사용 |

#### 한줄 요약
- 보조 정보를 공개해도 안전하다는 전제 위에 전체 구조가 서 있으므로, 그 전제가 흔들리면 저장하지 않는다는 이점이 통째로 사라진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **챌린지-응답(CRP, Challenge-Response Pair)**: 특정 입력 자극(Challenge)에 대해 PUF 회로가 고유하게 내놓는 출력값(Response)의 쌍.

</details>

```text
키 생성 요청 → PUF 코어에서 원시 응답 측정
        │
   헬퍼 데이터와 결합해 오류 비트 보정 시도
        │
   오류 개수가 정정 한계 안인가?
   ┌────┴─────┐
  예           아니오
   │             │
기준 응답 복원   키 재현 실패 → 재시도 또는 안전 상태
   │
키 유도 함수로 균등 엔트로피 키 생성
        │
   암호 연산 수행
        │
   키 버퍼·레지스터 즉시 제로화 후 잔류 검증
```

분기 결과: 정정 한계가 곧 동작 가능 환경 범위를 정하므로, 온도·전압 범위를 넓히려면 보조 정보를 늘려야 하고 그만큼 공개되는 정보도 함께 늘어남

#### 한줄 요약
- **챌린지-응답(CRP, Challenge-Response Pair)**을 매번 새로 계산한다는 점 때문에 이 방식은 저장 위험을 없앤 대신 재현 실패라는 새로운 실패 모드를 얻는다.

## Ⅴ. 종류 및 비교

| 하드웨어 보안 키 생성 기술 | SRAM PUF | Ring Oscillator PUF | eFuse OTP 저장 | TRNG (난수발생기) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 상용 MCU 온칩 SRAM 활용 초저비용 | FPGA 로직 셀 기반 PUF 구현 | 전통적인 제조사 고정 키 주입 | 실시간 일회용 세션키/난수 생성 |
| 핵심 특징 | 전원 인가 시 SRAM 셀의 초기 불안정 상태 활용 | 인버터 체인의 지연시간 차이로 주파수 비교 | 전기적 퓨즈를 영구 단선시켜 0/1 저장 | 열잡음/양자잡음 기반 예측불가 난수 |
| 한계 | 고온 장기 사용 시 셀 노화(Aging) 에러 증가 | 면적 및 전력 소모가 SRAM 대비 큼 | 물리적 레이저 프로빙/현미경 공격에 노출 | 매번 다른 난수가 나와 고정 키로 사용 불가 |

#### 한줄 요약
- 네 기술은 값이 고정인지 매번 달라지는지로 갈리며, 고정되면 저장 위험이 생기고 달라지면 키로 쓸 수 없다는 딜레마를 PUF가 중간에서 푼다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **머신러닝 모델링 공격(ML Modeling Attack)**: 공격자가 대량의 챌린지-응답 쌍(CRP)을 수집하여 인공지능 신경망으로 PUF의 하드웨어 물리 특성을 수학적으로 복제하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 온도·전압 변화로 키 재현 실패 | 환경별 오류율 측정 후 정정 부호와 불안정 비트 마스킹 적용 | 목표 실패 확률에 맞춘 정정 여유 확보 |
| 대량 응답 쌍 노출로 **머신러닝 모델링 공격(ML Modeling Attack)** 성립 | 입력단에 해시 차단막을 두어 직접 질의 차단 | 외부에서의 응답 쌍 수집 원천 봉쇄 |
| 소자 노화로 응답이 서서히 변화 | 수명 시험과 안정 비트 선별, 통제된 재등록 정책 | 장기 재현 실패와 재등록 악용 위험 완화 |
| 보조 정보 변조로 복원 경로에 오류 주입 | 헬퍼 데이터에 무결성 검증과 버전 확인 적용 | 비인가 보조 정보의 투입 차단 |

#### 한줄 요약
- 물리적으로 복제할 수 없다는 성질이 수학적으로 예측할 수 없다는 뜻은 아니므로, 모델링 공격 앞에서는 물리 보안이 아니라 질의 통제가 방어선이 된다.

## Ⅶ. 결론

- 저장된 키의 노출 위험을 없애야 하고 환경별 재현성이 검증됐다면 PUF와 퍼지 추출기를 적용하고, 강한 물리 공격과 실행 중 키 탈취까지 고려한다면 별도 보안 소자·탬퍼 센서·키 수명주기 통제와 함께 구성

#### 한줄 요약
- 키를 만드는 순간부터 지우는 순간까지는 여전히 메모리에 존재하므로, 저장하지 않는다는 이점은 실행 중 보호가 함께 있을 때만 온전해진다.
