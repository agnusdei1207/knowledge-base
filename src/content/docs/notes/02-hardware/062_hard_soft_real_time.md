## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 시스템(Real-Time System)**: 논리적 연산 결과의 정확성뿐만 아니라 결과가 반환되는 시간적 정확성(Timing Correctness)까지 만족해야 하는 시스템.
- **Deadline Miss(마감시간 초과)**: 시스템이 지정된 시간 제약 내에 연산을 완료하지 못하고 지연되는 상황.
- **Utility Function(효용 함수)**: 마감시간 경과에 따라 연산 결과의 가치가 어떻게 변화하는지(부의 가치, 0, 점진적 감소)를 나타내는 곡선.

</details>

- 정의/개념: 마감시간(Deadline) 위반 시 시스템에 미치는 치명도(인명/재산 손실)와 지연된 결과 데이터의 잔여 효용 가치(Utility Value) 감소 형태에 따라 실시간성을 하드(Hard), 펌(Firm), 소프트(Soft)로 구분하는 분류 체계
- 배경/필요성: 모든 시스템에 하드 실시간 제약을 무차별 적용하는 비용 과잉 투자를 방지하고, **워크로드 특성에 맞춘 최적의 스케줄링 및 결함 복구 전략 수립**

#### 한줄 요약

- 마감시간 위반 시 결과 가치와 시스템 영향도에 따라 **하드·펌·소프트 실시간으로 분류**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Timing Correctness(시간 정확성)**: 연산 값이 수학적으로 옳더라도 마감시간을 넘겨 출력되면 오류(Failure)로 처리하는 원칙.
- **Catastrophic Failure(치명적 실패)**: 하드 실시간 시스템에서 마감시간 위반 시 인명 사고나 기계 파손으로 직결되는 상태.
- **QoS Degradation(서비스 품질 저하)**: 소프트 실시간 시스템에서 마감시간 위반 시 화질 저하나 프레임 드롭으로 서비스를 유지하는 방식.

</details>

- 연산의 수학적 정답뿐만 아니라 마감시간 내 출력을 필수로 요구하는 **시간 정확성(Timing Correctness)**
- 마감시간 초과 시 결과 가치가 부(Negative, 재앙)로 곤두박질치는 **하드 실시간의 무관용 원칙**
- 지연된 결과를 버릴지(Firm: 0의 가치) 아니면 화질을 깎아 쓸지(Soft: 잔여 가치)에 따른 **유연한 효용 모델링**

#### 한줄 요약

- **시간 정확성(Timing Correctness)·마감시간 위반 영향도(Catastrophic/Zero/Degraded)·효용 함수 모델링**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Fail-Safe Mechanism**: 하드 실시간 시스템에서 마감시간 초과 또는 치명적 오류 감지 시 모터 전원을 차단하고 안전 정지 상태로 전환하는 방어 장치.
- **Dynamic QoS Controller**: 소프트 실시간 시스템에서 시스템 과부하 시 프레임 레이트나 해상도를 동적으로 낮춰 마감시간 만족률을 유지하는 제어기.

</details>

```text
[ 실시간 시스템 마감시간 감시 및 미스 처리 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 태스크 등록부 (주기 T_i, 실행시간 C_i, 마감시간 D_i 등록) │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 2. 실시간 스케줄러 (EDF, RM, 정적 우선순위 스케줄링)         │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 3. 데드라인 감시 타이머 (하드웨어 인터럽트 기반 런타임 추적)│
└──────────────────────────────┬──────────────────────────────┘
                               │ (Deadline Miss 발생 시)
             ┌─────────────────┼─────────────────┐
             ▼                                   ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ 4-1. Fail-Safe 비상 차단     │   │ 4-2. 결과 폐기 및 QoS 강하   │
│ (Hard RT : 비상 정지/셧다운) │   │ (Firm : Drop / Soft : 저화질)│
└──────────────────────────────┘   └──────────────────────────────┘
```

선의 의미: 태스크 등록, 실시간 스케줄러, 데드라인 감시 타이머 및 마감시간 위반 대응 정책(Hard/Firm/Soft) 간의 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 시간표 태스크 등록 | 몇 초마다 깨어나서 며칠까지 무조건 끝내야 하는지 데드라인 파라미터를 커널 스케줄러에 문신처럼 박아넣음 |
| 채찍질 실시간 스케줄러 | 에어백(Hard)인지 동영상(Soft)인지 타깃 속성에 맞춰 태스크 멱살을 잡고 우선순위 권력을 무자비하게 휘두름 |
| 데드라인 감시 타이머 | 째깍째깍 흐르는 런타임을 째려보다가 0.001초라도 마감을 넘기는 순간 경고 알람을 찢어지게 울림 |
| 삑사리 미스 대응 정책 | 지각했을 때 시스템 전원을 뽑을지(Hard), 늦은 데이터를 버릴지(Firm), 화질 렉을 걸지(Soft) 처리하는 판사 |

#### 한줄 요약

- **태스크 등록부·실시간 스케줄러·데드라인 감시 타이머·미스 대응 정책(Fail-Safe/Drop/QoS)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Drop Strategy(폐기 전략)**: 펌 실시간에서 마감시간이 지난 불필요한 패킷/태스크를 즉시 킬(Kill)하여 CPU와 메모리를 회수하는 기법.

</details>

```text
[ Deadline Miss 발생 시 3단계 의사결정 흐름 ]
                         │
                         ▼
   [ 1. 태스크 완료 시각 > 마감시간 (Deadline Miss 감지) ]
                         │
                         ▼
   [ 2. 마감시간 위반이 인명/시스템 파괴를 유발하는가? ]
        /                                       \
   [ 예 (치명적) ]                           [ 아니오 (비치명적) ]
        │                                       │
   [ 3. Hard RT : Fail-Safe 비상 정지 ]    [ 4. 지연된 데이터 가치가 0인가? ]
                                                /                 \
                                           [ 예 (가치 0) ]    [ 아니오 (잔여 가치) ]
                                                │                 │
                                           [ 5. Firm RT :     [ 6. Soft RT :
                                             결과 폐기(Drop) ]   QoS 다운 후 처리 ]
```

**동작 원리**

1. **미스 감지**: 타이머 감시기가 태스크의 완료 시점이 $D_i$를 초과했음을 감지
2. **치명성 평가**: 마감시간 위반이 시스템 파괴나 인명 사고로 이어지는지 1차 판정
3. **Hard RT 조치**: 치명적일 경우 즉시 Fail-Safe 모드로 전이하여 시스템을 안전 셧다운
4. **잔여 가치 평가**: 비치명적인 경우 지연된 데이터가 여전히 유용한지 판정
5. **Firm RT 조치**: 금융 틱 데이터처럼 지연 시 가치가 0이면 연산 결과를 즉시 폐기(Drop)
6. **Soft RT 조치**: 동영상 스트리밍처럼 지연되어도 쓸모가 있으면 화질을 낮춰 계속 렌더링

#### 한줄 요약

- 데드라인 미스 발생 $\to$ **치명도 판정 $\to$ 치명적 시 Fail-Safe 셧다운(Hard) $\to$ 데이터 무효 시 폐기(Firm) $\to$ 잔여 가치 시 QoS 강하(Soft)**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Hard vs Firm vs Soft Real-Time**:
  - Hard: 위반 시 치명적 재난 (Negative Utility), 에어백/ABS/원자로
  - Firm: 위반 시 결과 무효 (Utility = 0), 초단타 매매(HFT)/레이더
  - Soft: 위반 시 품질 저하 (Utility > 0), 스트리밍/온라인 게임

</details>

| 비교 항목 | 하드 실시간 (Hard Real-Time) | 펌 실시간 (Firm Real-Time) | 소프트 실시간 (Soft Real-Time) |
|:---|:---|:---|:---|
| 마감시간 위반 시 결과 가치 | 부(Negative)의 가치 (치명적 재난) | 가치 = 0 (완전 무효화, 쓰레기 데이터) | 가치 점진적 감소 ($>0$, 품질 저하) |
| 시스템 영향 및 대응 | 치명적 인명/재산 손실, Fail-Safe 셧다운 | 시스템 고장은 없으나 해당 결과 즉시 폐기 | 사용자 체감 품질(QoS) 저하, 계속 재생/처리 |
| 대표 적용 분야 | 자동차 에어백/ABS, 항공기 제어, 원자로 | 주식 초단타 매매(HFT), 레이더 추적 | 비디오 스트리밍, 온라인 게임, 웹 서빙 |

#### 한줄 요약

- 치명적 인명 손실은 **Hard RT**, 데이터 무효화는 **Firm RT**, 품질 저하는 **Soft RT**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Safety Impact Analysis(안전성 영향 분석)**: ISO 26262 ASIL 등급에 따라 마감시간 위반의 위험도를 정량화하여 Hard/Firm/Soft 설계 기준을 수립하는 평가.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **하드 실시간** 태스크가 어쩌다 1번 지각했는데 차가 벽에 박아 운전자가 사망하는 대형 참사 발생 | 타이머가 절대 늦을 수 없음을 수학적으로 증명하고 뼛속까지 깐깐한 데드라인 충족을 무조건 사전 입증 | 어떠한 재수 없는 억까 상황에서도 제시간에 브레이크가 밟히는 절대 생존 보장 100% 확보 |
| **펌 실시간** 태스크가 이미 늦어 쓰레기가 된 데이터를 연산하느라 쓸데없이 CPU와 메모리 낭비 | 데드라인 미스 나는 순간 바로 멱살 잡고 태스크 킬 한 뒤 데이터 가차 없이 쓰레기통에 **결과 폐기** | 뻘짓하는 연산 자원을 1초 만에 즉시 회수하여 다음 타임슬롯 준비태세 쾌속 확립 |
| **소프트 실시간** 태스크 지연이 계속 쌓여서 넷플릭스 서버 전체가 메모리 부족으로 뻗어버리는 마비 | 프레임을 뚝뚝 끊어 버리거나 화질(QoS)을 144p로 박살 내버리는 다이내믹 품질 하향 스케일링 강제 | 고객이 욕은 좀 하더라도 서버가 터져서 뉴스에 나오는 서비스 전면 중단 굴욕 차단 |

#### 한줄 요약

- **정적 시간 분석(WCET 입증)·지각 태스크 조기 폐기(Drop)·동적 QoS 스케일링**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **도메인 특화 실시간 설계**: 단일 제어기 내에서도 모터 토크 제어는 Hard RT, 센서 텔레메트리 로깅은 Soft RT로 분할하여 이종 스케줄링 구현.

</details>

- 시스템 엔지니어링 설계 시 **안전 필수(Safety-Critical) 기능은 Hard RT, 시계열 트랜잭션은 Firm RT, 멀티미디어는 Soft RT 표준 채택**

#### 한줄 요약

- **마감시간 초과 시의 파급력과 효용 함수 곡선**에 기반한 실시간 등급 판정
