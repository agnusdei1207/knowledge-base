## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 실시간 제어 태스크에서 연산 결과가 유효성과 안전성을 갖추기 위해 반드시 완수되어야 하는 엄격한 시간적 한계점.
- **시간-효용 함수(Time-Utility Function, TUF)**: 작업 완료 시점에 따라 시스템 전체에 기여하는 유효 가치(Utility Value)의 변화를 나타내는 수학적 함수 모델.

</details>

- 정의/개념: 태스크의 **마감시간(Deadline)** 미스 발생 시 **시간-효용 함수(TUF)**의 감쇄 형태와 파급 위험도에 따라 시스템을 3단계로 분류하는 **실시간 시스템 분류 체계**
- 배경/필요성: 실시간 제어 시스템의 태스크별 마감시간(Deadline) 위반 시 초래되는 **시스템 파급 위험도(치명적 실패 vs 효용 소멸 vs 서비스 품질 저하)에 따른 차등적 자원 스케줄링 및 안전 설계** 필요

#### 한줄 요약
- 실시간 시스템은 마감시간 위반 시 효용이 음수(치명적 재난)가 되는 하드, 0(무가치)이 되는 펌, 점진 감쇄하는 소프트로 분류된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드 마감시간(Hard Deadline)**: 마감시간 초과를 시스템 요구사항 위반으로 판정하는 시간 제약.
- **서비스 품질 저하(Graceful Degradation)**: 소프트 실시간 환경에서 지연 발생 시 시스템이 정지되지 않고 해상도나 프레임 레이트를 낮추어 지속 서비스하는 기법.

</details>

- 하드 실시간 (Hard Real-Time): 마감시간 미스를 **시스템 실패**로 판정하는 엄격한 시간 제약
- 펌 실시간 (Firm Real-Time): 마감시간을 넘긴 연산 결과는 **효용 가치**가 0으로 간주되어 즉시 폐기(Drop)되나 시스템 자체는 정상 유지
- 소프트 실시간 (Soft Real-Time): 마감시간을 초과해도 유효성이 완전히 소멸하지 않고 **효용 가치**가 완만하게 감쇄하여 서비스 품질 저하(QoS) 수용

#### 한줄 요약
- 하드는 안전을 위한 절대 마감 준수, 펌은 무가치 데이터 즉시 폐기, 소프트는 점진적 서비스 품질 완화를 원칙으로 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 프로세서의 캐시 미스, 파이프라인 정체 등 최악의 조건을 가정했을 때 특정 코드가 완료되는 데 걸리는 최대 실행 시간.
- **페일 세이프 모드(Fail-Safe Mode)**: 하드 실시간 마감시간 위반 감지 시 시스템을 안전한 정지 상태나 백업 제어로 강제 전환하는 안전 메커니즘.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 마감시간 | 태스크 결과의 **시간 유효성** 경계 정의 |
| 시간-효용 함수 | 완료 시점별 **효용 변화** 모델링 |
| 마감 미스 정책 | 실패·폐기·품질 저하의 **후속 조치** 결정 |

#### 한줄 요약
- 하드(재난 방지), 펌(무가치 데이터 폐기), 소프트(QoS 저하 수용)는 상이한 효용 곡선과 오류 복구 메커니즘을 가진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **폴백 제어(Fallback Control)**: 센서 연산이 마감시간 내에 끝나지 못했을 때 직전 주기의 안전 제어값을 재사용하거나 비상 기본값으로 대체하는 기법.

</details>

```text
외부 센서 이벤트 및 제어 데이터 수신
                      │
                      ▼
1. 실시간 범주 판정
                      │
                      ▼
2. 마감시간 판정
   ┌──────────────────┴──────────────────┐
[ 마감시간 내 완료 (Success) ]         [ 마감시간 초과 발생 (Deadline Miss) ]
   │                                     │
   ▼                                     ▼
정상 제어 출력                          3. 마감 미스 처리
   │                                     ┌──────────┼──────────────────────┐
   │                                  [ 하드 ]    [ 펌 ]                [ 소프트 ]
   │                                     │          │                      │
   │                                     ▼          ▼                      ▼
   │                                  안전 상태 전환  계산 결과 폐기      품질 저하 수용
   │                                     정지 또는   ➔ 다음 주기 대기        ➔ 적응형 품질 조정
   │                                     폴백 진입                           (프레임 드롭)
   │                                     │          │                      │
   └─────────────────────────────────────┴──────────┴──────────────────────┘
```

**동작 원리**

1. **실시간 범주 판정**: 마감 미스의 효용과 위험에 따라 범주 선택
2. **마감시간 판정**: 완료 시점과 태스크 마감시간 비교
3. **마감 미스 처리**: 하드는 실패 대응, 펌은 폐기, 소프트는 품질 완화

#### 한줄 요약
- 갈래를 가르는 것은 처리 속도가 아니라 마감 미스의 대가가 안전 사고인지 품질 저하인지이므로, 전부를 하드로 설계하면 자원을 과잉 투입하고 뭉뚱그리면 안전 태스크를 잃는다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 하드 실시간 (Hard RT) | 펌 실시간 (Firm RT) | 소프트 실시간 (Soft RT) | 비실시간 (Non Real-Time) |
|:---|:---|:---|:---|:---|
| 시간 제약성 | 미스가 **시스템 실패** | 미스 결과의 효용 소멸 | 미스 후 **효용 점진 감소** | 마감시간 비핵심 |
| 마감 미스 대책 | **Fail-Safe 비상 정지** 및 폴백 | **데이터 즉각 폐기(Drop)** | 적응형 버퍼링, QoS 완화 | 재시도 및 완료 대기 |
| 성능 검증 방식 | WCET·WCRT 상한 분석 | 마감 미스율·폐기율 관리 | 지연 분포·QoS 관리 | 처리량·평균 지연 관리 |
| 운영체제 환경 | **인증된 RTOS**(VxWorks, QNX) | RTOS 또는 저지연 Linux | 범용 OS (Linux, Android) | 범용 서버 OS (Batch 시스템) |

#### 한줄 요약
- 인명 안전 시스템은 하드, 유효 기간이 극히 짧은 센서 데이터는 펌, 사용자 경험 중심 서비스는 소프트 실시간을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **시간 분할 다중화(Time-Division Multiplexing, TDM)**: 하드 실시간 태스크와 소프트 태스크가 실행 시간을 타임슬롯별로 엄격히 분할하여 상호 간섭을 차단하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하드 태스크의 마감시간 미스 위험 | **TDM 기반 하드웨어 파티셔닝(ARINC 653)** 적용 | 하드 태스크의 결정론적 실행 시간 격리 보장 |
| 펌 태스크 지연 누적으로 버퍼 넘침 | **순환 버퍼(Circular Buffer)** 기반 덮어쓰기 정책 | 버퍼 넘침 차단 및 최신 데이터 즉각성 사수 |
| 소프트 스트리밍 대역폭 변동 | **적응형 비트레이트(ABR)** 및 동적 버퍼링 적용 | 재생 끊김 방지 및 체감 품질 극대화 |

#### 한줄 요약
- 실무에서는 TDM 파티셔닝으로 하드 태스크를 격리하고, 링버퍼로 펌 데이터를 갱신하며, ABR로 소프트 스트리밍을 안정화한다.

## Ⅶ. 결론

- 인명/안전 직결 제어(차량/항공/의료)는 **하드 실시간(WCET 보장 Fail-Safe)**, 금융 트레이딩/센싱은 **펌 실시간(폐기 처리)**, 멀티미디어는 **소프트 실시간(QoS 완화)**으로 명확히 구분 설계하며, 현대 복합 시스템은 **혼합 임계도(Mixed-Criticality) 아키텍처를 적용하여 하드/소프트 태스크를 시공간적으로 완전 격리(ARINC 653/하이퍼바이저)**하는 추세

#### 한줄 요약
- 실시간 시스템은 마감시간 미스의 파급력에 따라 하드·펌·소프트를 계층 분리하고, 전용 복구 정책을 차별화하여 완성된다.
