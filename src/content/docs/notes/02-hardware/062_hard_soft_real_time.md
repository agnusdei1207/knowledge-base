## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 실시간 시스템에서 특정 태스크의 연산 결과가 유효성을 유지하기 위해 완수되어야 하는 엄격한 시간 한계.
- **효용 함수(Utility Function)**: 작업 완료 시점에 따라 시스템에 제공되는 가치(Value)나 유용성의 크기를 나타내는 수학적 모델.

</details>

- 정의/개념: **마감시간(Deadline)** 초과 시 **효용 함수**의 감쇄 형태와 파급 위험도에 따라 시스템을 분류하는 실시간 체계
- 배경/필요성: 동일한 실시간 지연 잣대 적용 시 **핵심 안전 태스크 보호 실패 및 과도한 자원 낭비 방지 불가**

#### 한줄 요약
- 실시간 시스템은 마감시간 위반 시 효용이 음수(재난)가 되는 하드, 0(무가치)이 되는 펌, 점진 감소하는 소프트로 분류된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드 마감시간(Hard Deadline)**: 단 한 번의 마감시간 위반도 허용되지 않으며 위반 시 치명적 사고가 발생하는 엄격한 시간 제약.
- **QoS 저하(Graceful Degradation)**: 소프트 실시간 환경에서 지연 발생 시 서비스가 중단되는 대신 화질 저하 등으로 품질을 점진적으로 낮추는 기법.

</details>

- 하드 실시간: **하드 마감시간** 준수가 필수이며 위반 시 시스템 파국 및 안전 사고 유발
- 펌 실시간: 마감시간을 초과한 데이터는 **효용 가치 0**으로 간주되어 즉시 폐기
- 소프트 실시간: 마감시간 초과 후에도 유효성이 유지되며 점진적 **QoS 저하** 허용

#### 한줄 요약
- 하드는 안전을 위한 절대 마감 준수, 펌은 무가치 데이터 즉시 폐기, 소프트는 점진적 서비스 품질 완화를 원칙으로 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **효용 곡선(Time-Utility Curve)**: 시간 경과에 따른 가치 변화를 시각화한 그래프로, Hard는 음의 무한대, Firm은 0으로 수직 낙하, Soft는 점진 감쇄 곡선을 가짐.

</details>

```text
[마감시간(Deadline) 이후 효용 변화]
|-- 마감시간 이전 : 세 범주 모두 100% 정상 효용 유지
`-- 마감시간 이후
    |-- 소프트 실시간 : 효용 완만하게 점진 감소 (스트리밍·온라인 게임)
    |-- 펌 실시간     : 효용 즉시 0으로 수직 하락 및 폐기 (금융 시세·추적)
    `-- 하드 실시간   : 효용 음의 무한대(재난) 전환 (ABS·에어백·원전 제어)
```

선의 의미: 계층 및 시간 경과에 따른 효용 특성

| 구성요소 | 책임 |
|:---|:---|
| 하드 실시간 | 최악 응답 시간(WCRT) 분석을 통해 마감시간 내 완수를 수학적으로 사전 입증 |
| 펌 실시간 | 마감 초과 데이터를 즉시 드롭하고 최신 데이터 획득 루프로 복귀 |
| 소프트 실시간 | 적응형 버퍼링과 품질 조절로 사용자 체감 지연 완화 |
| 감시 타이머 | 태스크 실행 시간 계측 및 마감시간 초과 시 예외 처리 인터럽트 발생 |
| 안전 상태 전환기 | 하드 실시간 위반 감지 시 사전 정의된 페일 세이프(Fail-Safe) 모드로 전환 |

#### 한줄 요약
- 하드, 펌, 소프트는 서로 다른 시간-효용 곡선을 가지며 이에 맞춰 스케줄링 및 예외 복구 방식을 차별화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **폴백(Fallback)**: 제어 연산 마감시간 초과 시 이전 안전 제어값을 재사용하거나 기본값으로 전환하는 비상 기법.

</details>

```text
이벤트·센서 데이터 수신
        │
   태스크의 마감시간 범주 확인 후 선점 스케줄링
        │
   마감시간 안에 완료됐는가?
   ┌────┴─────┐
  예           아니오
   │             │
정상 출력·      어느 범주인가?
액추에이터 구동  ┌────┼──────┐
   │          하드     펌      소프트
   │           │       │        │
   │      안전 정지  결과 폐기  지연 결과 수용
   │      또는 폴백  후 다음     후 품질 조정
   │       진입      주기 대기      │
   └────┬──────┴───────┴──────────┘
        │
   위반 빈도 모니터링 및 자원 재할당
```

#### 한줄 요약
- 마감시간 초과 시 하드는 안전 페일 세이프로 진입하고, 펌은 데이터를 버리며, 소프트는 지연된 결과를 수용하고 QoS를 조정한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **비실시간(Non Real-Time)**: 마감시간 개념이 없으며 시스템 총 처리량(Throughput) 극대화를 목표로 하는 배치 환경.

</details>

| 실시간 시스템 범주 | 하드 실시간 (Hard RT) | 펌 실시간 (Firm RT) | 소프트 실시간 (Soft RT) | 비실시간 (Non RT) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 차량 ABS, 에어백, 원전 제어, 항공 항법 | 초단타 주식 거래, 레이더 타깃 추적 | 동영상 스트리밍, 온라인 게임, 웹 서버 | 배치 데이터 분석, 컴파일러, 문서 편집 |
| 핵심 특징 | 마감시간 미스 시 시스템 전체 붕괴 및 인명 사고 | 마감 초과 결과는 효용 0 (즉시 폐기) | 마감 초과 시 품질 저하(QoS), 동작 유지 | 마감시간 개념 부재, 총 처리량(Throughput) 중심 |
| 한계 | WCET 입증 및 정적 분석 난이도 극상 | 잦은 데이터 드롭 시 제어 연속성 저하 | 사용자 경험(UX) 불만족 및 지연 누적 | 응답 시간 예측 불가 및 실시간 제어 불가 |

#### 한줄 요약
- 인명 안전과 직결된 시스템은 하드, 유효 기간이 짧은 금융/센서는 펌, 멀티미디어 서비스는 소프트 실시간을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **지터(Jitter)**: 주기적 태스크의 실행 시작 또는 완료 시각이 기준 주기에서 벗어나는 시간적 변동 편차.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하드 태스크의 최악 응답 시간 마감 초과 | WCET 기반 응답 시간 분석 및 **지터(Jitter)** 억제 | 배포 전 마감시간 위반 가능성 원천 제거 |
| 펌 태스크에서 지연 누적으로 큐 오버플로 | 지연 패킷 드롭 정책 및 최신 프레임 갱신 메커니즘 | 최신성 유지 및 누적 버퍼 지연 해소 |
| 소프트 태스크의 네트워크 지연으로 인한 끊김 | 적응형 비트레이트(ABR) 및 동적 버퍼링 적용 | 스트리밍 연속성 유지 및 체감 품질 개선 |
| 하드와 소프트 태스크 간 자원 경합 간섭 | 시간 분할 다중화(TDM) 및 메모리 영역 하드웨어 격리 | 하드 태스크의 결정론적 실행 시간 완전 격리 보장 |

#### 한줄 요약
- 하드는 WCET 정적 분석으로 마감을 보장하고, 펌은 패킷 드롭으로 큐를 비우며, 소프트는 적응형 버퍼링으로 대응한다.

## Ⅶ. 결론

- 인명·설비 안전 태스크는 **하드 실시간(WCRT 사전 검증)**, 최신성 중심 데이터는 **펌 실시간(초과 시 폐기)**, 일반 서비스는 **소프트 실시간(QoS 제어)**으로 분리 설계

#### 한줄 요약
- 실시간 아키텍처는 마감시간 초과 시의 시스템 영향도에 따라 계층을 분리하고 상이한 자원 할당과 오류 복구 정책을 적용해야 한다.
