## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 실시간 제어 태스크에서 연산 결과가 유효성과 안전성을 갖추기 위해 반드시 완수되어야 하는 엄격한 시간적 한계점.
- **시간-효용 함수(Time-Utility Function, TUF)**: 작업 완료 시점에 따라 시스템 전체에 기여하는 유효 가치(Utility Value)의 변화를 나타내는 수학적 함수 모델.

</details>

- 정의/개념: 태스크의 **마감시간(Deadline)** 미스 발생 시 **시간-효용 함수(TUF)**의 감쇄 형태와 파급 위험도에 따라 시스템을 3단계로 분류하는 실시간 시스템 분류 체계
- 배경/필요성: 실시간 제어 시스템의 태스크별 마감시간(Deadline) 위반 시 초래되는 치명적 재난, 데이터 효용 소멸 및 **서비스 품질 저하 위험 방어 한계**

#### 한줄 요약
- 실시간 시스템은 마감시간 위반 시 효용이 음수(치명적 재난)가 되는 하드, 0(무가치)이 되는 펌, 점진 감쇄하는 소프트로 분류된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드 마감시간(Hard Deadline)**: 마감시간 초과를 시스템 요구사항 위반으로 판정하는 시간 제약.
- **서비스 품질 저하(Graceful Degradation)**: 소프트 실시간 환경에서 지연 발생 시 시스템이 정지되지 않고 해상도나 프레임 레이트를 낮추어 지속 서비스하는 기법.

</details>

- 하드 실시간 (Hard Real-Time): 마감시간 미스를 시스템 실패로 판정하는 엄격한 시간 제약
- 펌 실시간 (Firm Real-Time): 마감시간을 넘긴 연산 결과는 효용 가치가 0으로 간주되어 즉시 폐기(Drop)되나 시스템 자체는 정상 유지
- 소프트 실시간 (Soft Real-Time): 마감시간을 초과해도 유효성이 완전히 소멸하지 않고 효용 가치가 완만하게 감쇄하여 **서비스 품질 저하**(QoS) 수용

#### 한줄 요약
- 하드는 안전을 위한 절대 마감 준수, 펌은 무가치 데이터 즉시 폐기, 소프트는 점진적 서비스 품질 완화를 원칙으로 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 프로세서의 캐시 미스, 파이프라인 정체 등 최악의 조건을 가정했을 때 특정 코드가 완료되는 데 걸리는 최대 실행 시간.
- **페일 세이프 모드(Fail-Safe Mode)**: 하드 실시간 마감시간 위반 감지 시 시스템을 안전한 정지 상태나 백업 제어로 강제 전환하는 안전 메커니즘.

</details>

```text
[실시간 시스템 범주 및 효용 체계]
  │
  ├─ [하드 실시간] (Hard Real-Time)
  │     ├─ [마감시간 특성] (엄격한 시간 제약, 미스 시 시스템 실패)
  │     ├─ [효용 변화: TUF] (마감 초과 시 효용 음수 폭락, 재난)
  │     └─ [대응 메커니즘] (WCET 사전 증명, 페일세이프 비상 정지)
  │
  ├─ [펌 실시간] (Firm Real-Time)
  │     ├─ [마감시간 특성] (초과 시 결과 가치 상실, 시스템 정상)
  │     ├─ [효용 변화: TUF] (마감 초과 즉시 효용 0으로 절단)
  │     └─ [대응 메커니즘] (지연 패킷 즉각 폐기 Drop 및 재동기)
  │
  └─ [소프트 실시간] (Soft Real-Time)
        ├─ [마감시간 특성] (평균 응답성 중심, 통계적 준수)
        ├─ [효용 변화: TUF] (마감 초과 후에도 점진적 효용 감쇄)
        └─ [대응 메커니즘] (서비스 품질 완화, QoS 레벨 강등)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 마감시간 | 태스크 결과의 시간 유효성 경계 정의 |
| 시간-효용 함수 | 완료 시점별 효용 변화 모델링 |
| 마감 미스 정책 | 실패·폐기·품질 저하의 후속 조치 결정 |

#### 한줄 요약
- 하드(재난 방지), 펌(무가치 데이터 폐기), 소프트(QoS 저하 수용)는 상이한 효용 곡선과 오류 복구 메커니즘을 가진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마감 미스 핸들러(Deadline Miss Handler)**: 타이머 인터럽트 감시를 통해 태스크가 지정된 마감시간을 초과했을 때 시스템 안전을 위해 즉각 호출되는 예외 처리 루틴.
- **페일 세이프 폴백(Fail-Safe Fallback)**: 하드 실시간 연산 실패 시 직전 주기 안전 제어값 재사용, 비상 브레이크 작동 등 기정의된 안전 상태로 전환하는 제어 기법.

</details>

```text
[외부 센서 이벤트 및 제어 데이터 인입]
                     │
                     ▼
1. 시스템 태스크별 실시간 범주(Hard / Firm / Soft) 판정
                     │
                     ▼
2. 제어 태스크 실행 및 마감시간(Deadline D) 경과 여부 모니터링
    ┌────────────────┴────────────────┐
 [ 마감시간 내 정상 완료 (t <= D) ]  [ 마감시간 초과 발생 (t > D) ]
    │                                 │
    ▼                                 ▼
출력 포트로 정상 제어값 전송          3. 실시간 범주별 마감 미스(Deadline Miss) 분기
    │                                 ┌───────┼───────┐
    │                              [ 하드 ] [ 펌 ]  [ 소프트 ]
    │                                 │       │       │
    │                                 ▼       ▼       ▼
    │                              4. 안전  4. 결과 4. 해상도
    │                                 정지    폐기    감쇄 수용
    │                                 폴백    다음    (프레임
    │                                 진입    주기    드롭)
    │                                 │       │       │
    │                                 └───────┴───────┘
    │                                         │
    ▼                                         ▼
5. 시스템 상태 복구 및 다음 제어 사이클 개시
```

- 분기 결과: 마감시간 초과 시 하드는 즉각 페일 세이프 폴백으로 전환하며, 펌은 무효화된 패킷을 버리고, 소프트는 동적 QoS를 낮추어 서비스를 지속함

**동작 원리**

1. 시스템 설계 명세에 따른 인입 이벤트 태스크 위험도 분석 및 하드·펌·소프트 실시간 속성 분류
2. 선점형 스케줄러의 태스크 디스패치 및 타이머 인터럽트를 통한 마감시간(D) 내 완수 여부 실시간 추적
3. 마감시간 내 미완료 초과 확정 시 커널 마감 미스 예외 핸들러 가동 및 태스크 유형별 분기 수행
4. 하드 실시간의 페일 세이프 루틴 호출 비상 정지, 펌 실시간의 무효 연산 버퍼 즉시 폐기(Drop), 소프트 실시간의 버퍼 및 QoS 조정을 통한 시스템 부하 완화
5. 시스템 상태 복구 절차 수행 및 워치독 타이머 갱신을 통한 차기 실행 주기 준비

#### 한줄 요약
- 갈래를 가르는 것은 처리 속도가 아니라 마감 미스의 대가가 안전 사고인지 품질 저하인지이므로, 전부를 하드로 설계하면 자원을 과잉 투입하고 뭉뚱그리면 안전 태스크를 잃는다.

## Ⅴ. 종류 및 비교

| 대상 구분 | 하드 실시간 (Hard RT) | 펌 실시간 (Firm RT) | 소프트 실시간 (Soft RT) | 비실시간 (Non Real-Time) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 마감 미스 시 인명 피해나 시스템 파괴를 초래하는 제어 시스템 구축 시 | 마감 초과 시 결과 가치가 0이 되어 즉시 폐기해야 하는 금융/센서 환경 시 | 마감 미스 시 경미한 품질 저하는 허용되나 연속 재생이 중요한 스트리밍 시 | 마감시간 제약이 없고 배치 연산의 전체 무결성 및 처리량이 중요한 작업 시 |
| 핵심 특징 | 미스가 치명적 시스템 실패, Fail-Safe 비상 정지 및 폴백, WCET/WCRT 상한 엄격 보장, 인증 RTOS 환경 | 미스 결과의 효용 즉시 소멸, 데이터 즉각 폐기(Drop), 마감 미스율 관리, 저지연 Linux/RTOS 환경 | 미스 후 효용 완만 감소, 적응형 버퍼링 및 QoS 완화 수용, 지연 분포 관리, 범용 OS 환경 | 마감시간 비핵심, 완료 대기 및 자동 재시도, 처리량 및 평균 지연 관리, 범용 서버 OS 환경 |
| 한계 | 과잉 프로비저닝에 따른 하드웨어 BoM 비용 상승 및 유연성 부족 | 연속 미스 발생 시 제어 연속성 단절 및 데이터 신선도 저하 | 사용자 체감 품질(QoE) 저하 및 극단적 네트워크 지연 시 서비스 단절 위험 | 응답 시간 불확정성으로 인한 실시간 상호작용 시스템 적용 불가 |

#### 한줄 요약
- 인명 안전 시스템은 하드, 유효 기간이 극히 짧은 센서 데이터는 펌, 사용자 경험 중심 서비스는 소프트 실시간을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **시간 분할 다중화(Time-Division Multiplexing, TDM)**: 하드 실시간 태스크와 소프트 태스크가 실행 시간을 타임슬롯별로 엄격히 분할하여 상호 간섭을 차단하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하드 태스크의 마감시간 미스 위험 | **TDM 기반 하드웨어 파티셔닝(ARINC 653)** 적용 | 하드 태스크의 결정론적 실행 시간 격리 보장 |
| 펌 태스크 지연 누적으로 버퍼 넘침 | **순환 버퍼(Circular Buffer)** 기반 덮어쓰기 정책 | 버퍼 넘침 차단 및 최신 데이터 즉각성 사수 |
| 소프트 스트리밍 대역폭 변동 | **적응형 비트레이트(ABR)** 및 동적 버퍼링 적용 | 재생 끊김 방지 및 체감 품질 극대화 |

#### 한줄 요약
- 실무에서는 **TDM** 파티셔닝으로 하드 태스크를 격리하고, 링버퍼로 펌 데이터를 갱신하며, ABR로 소프트 스트리밍을 안정화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **혼합 임계도(Mixed-Criticality)**: 서로 다른 안전 무결성 수준을 요구하는 하드·소프트 실시간 태스크를 단일 SoC 내에서 시공간적으로 완전 격리하여 동시 구동하는 아키텍처 기법.
- **기능 안전(Functional Safety)**: 전기·전자 시스템의 하드웨어 결함이나 소프트웨어 오동작으로 인한 시스템 고장 위험을 허용 한도 이하로 통제하는 국제 안전 표준 체계.

</details>

- 인명 안전 중심의 하드 실시간부터 데이터 즉시 폐기형 펌 실시간, 품질 완화형 소프트 실시간의 계층적 구분과 함께, 단일 실리콘 내에서 이들을 시공간적으로 완전 격리 구동하는 혼합 임계도 하이퍼바이저 아키텍처로의 진화 추세.
- 태스크 실패 파급도에 따른 최악 실행 시간(WCET) 사전 증명과 함께, 도메인별 페일 세이프 폴백 및 적응형 서비스 완화 메커니즘을 차등화하는 기능 안전 거버넌스 확보 필요.

#### 한줄 요약
- 혼합 임계도 아키텍처 기반의 엄격한 시공간 격리와 파급도별 차등화된 폴백 정책을 수립하여 시스템 안전성과 자원 효율성을 동시 달성해야 한다.
