## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 시스템(Real-Time System)**: 1+1=2라는 계산이 맞는 것뿐만 아니라, "0.1초 안에 답을 내라"는 깐깐한 시간제한까지 맞춰야 인정해 주는 피곤한 시스템이다.
- **데드라인 미스(Deadline Miss)**: "0.1초 안에 에어백 터뜨려!"라고 했는데 0.15초에 터뜨리는 등, 정해진 마감시간을 넘겨버려 파국을 초래하는 지각 사태이다.
- **결과 가치(Result Value)**: 늦게 도착한 답안지가 사람을 살리는지(하드), 쓰레기통행인지(펌), 아쉬운 대로 쓸 수 있는지(소프트) 따지는 냉혹한 효용성 잣대이다.

</details>

- 정의: 마감시간 초과(**데드라인 미스**) 시 사람 목숨이 날아가는 파급력과 지연된 **결과 가치**의 떡락 형태에 따라 실시간의 급을 나누는 3단 분류 체계
- 배경: 넷플릭스 영상 좀 끊겼다고 전투기 미사일 방어 체계처럼 비싼 돈을 떡칠해 무조건적인 0.001초 마감 통제를 거는 멍청한 과잉 설계를 막기 위함

#### 한줄 요약

- 컴퓨터가 지각했을 때, 사람이 죽으면 하드(Hard), 데이터만 쓰레기가 되면 펌(Firm), 영상 화질만 떨어지면 소프트(Soft) 실시간으로 급을 나눈다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시간 정확성(Timing Correctness)**: 답이 아무리 완벽하게 맞아도, 타이머가 울린 뒤에 답을 제출하면 0점 처리하고 가차 없이 뺨을 때리는 시스템의 속성이다.
- **시스템 실패(System Failure)**: 단 1번의 데드라인 미스로 비행기가 추락하거나 자동차가 벽에 박는, 복구 불가능한 치명적 파국 상태이다.
- **품질 저하(Quality Degradation)**: 유튜브 4K 영상이 늦게 로딩될 때 서버를 끄는 대신 화질을 480p로 뭉개버리며 아쉬운 대로 서비스를 유지하는 꼼수이다.

</details>

- 계산이 아무리 완벽해도 정해진 시간보다 0.1초라도 늦으면 틀렸다고 가차 없이 실격 처리하는 **시간 정확성**을 최우선 요구함.
- 태스크 특성에 따라 단 1번의 삑사리(지각)도 끔찍한 인명 사고와 치명적인 **시스템 실패**로 격상하여 잔인하게 판정함.
- 마감시간을 넘겼을 때 쓰레기통에 처박을지(사장) 버퍼링을 돌리며 참아줄지(**품질 저하**)를 시스템 성격에 맞게 융통성 있게 수용함.

#### 한줄 요약

- 타이밍이 곧 생명이므로, 늦게 낸 정답은 오답으로 치부하되, 그 오답이 폭탄인지 쓰레기인지에 따라 대우를 다르게 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **태스크 등록(Task Registration)**: "이 프로세스는 0.05초마다 돌고 0.02초 안에 무조건 끝나야 함"이라고 스케줄러 장부에 뼛속 깊이 새겨 넣는 신고 절차이다.
- **실시간 스케줄러(Real-Time Scheduler)**: 누가 먼저 밥(CPU)을 먹을지 계급순으로 멱살 잡고 줄을 세우며, 늦장 부리면 걷어차는 잔혹한 커널 통제관이다.
- **데드라인 감시(Deadline Monitoring)**: 각 태스크 옆에 타이머를 들고 서서, 0.001초라도 마감을 넘기는 순간 비상벨을 찢어지게 울리는 감시 카메라이다.
- **미스 대응 정책(Miss-Handling Policy)**: 태스크가 지각했을 때 전원을 뽑을지(차단), 늦은 답을 찢어버릴지(폐기), 렉을 유발할지(QoS 강하) 심판하는 판사이다.

</details>

```text
[ 실시간 운영체제 깐깐한 타이머 감시 및 지각생 처리 프레임워크 ]
[ 1. 시간표 태스크 등록 ] ▶ [ 2. 멱살 잡는 실시간 스케줄러 ]
                                         │
                                         ▼
                            [ 3. 째깍째깍 데드라인 감시 ]
                                         │
                 (앗! 지각이다)            ▼
                 +----------- [ 4. 삑사리 미스 대응 정책 ] -----------+
                 │                       │                       │
                 ▼                       ▼                       ▼
       [ 멈춰! 시스템 셧다운 ]      [ 늦었어! 결과 폐기 ]     [ 렉 걸어! 화질 뭉개기 ]
         (하드 실시간)             (펌 실시간)             (소프트 실시간)
```

| 구성요소 | 책임 |
|:---|:---|
| 시간표 **태스크 등록** | 몇 초마다 깨어나서 며칠까지 무조건 끝내야 하는지 데드라인 파라미터를 커널 스케줄러에 문신처럼 박아넣음 |
| 채찍질 **실시간 스케줄러** | 에어백(Hard)인지 동영상(Soft)인지 타깃 속성에 맞춰 태스크 멱살을 잡고 우선순위 권력을 무자비하게 휘두름 |
| **데드라인 감시** 타이머 | 째깍째깍 흐르는 런타임을 째려보다가 0.001초라도 마감을 넘기는 순간 경고 알람을 찢어지게 울림 |
| 삑사리 **미스 대응 정책** | 지각했을 때 시스템 전원을 뽑을지(Hard), 늦은 데이터를 버릴지(Firm), 화질 렉을 걸지(Soft) 처리하는 판사 |

#### 한줄 요약

- 스케줄러가 타이머를 들고 감시하다가, 태스크가 지각(미스)하면 시스템의 급(하드/펌/소프트)에 맞춰 징벌(대응 정책)을 내린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **완료 시각(Completion Time)**: 태스크가 헉헉대며 계산을 끝마치고 "나 다 했소!"라며 커널에 답안지를 제출한 실제 시간(타임스탬프)이다.
- **결과 폐기(Result Discard)**: 주식 호가처럼 0.1초만 늦어도 가치가 '0'이 되는 데이터를 쳐다보지도 않고 쓰레기통에 처박아버리는 무자비한 동작이다.
- **안전 상태(Fail-Safe State)**: 에어백 펌웨어가 뻗었을 때 모터가 폭주하지 않게, 즉시 전원을 끊고 시스템을 강제 셧다운 시키는 방어 기제이다.

</details>

```text
[ 데드라인 삑사리(Miss) 시 치명도 폭발 파급력에 따른 잔인한 3단 분기 흐름 ]
                               │
                               ▼
        [ 1. 데드라인 미스 발생 시, 사람 죽는지 기계 부서지는지 1차 치명성 판정 ]
                  /                                   \
             (용서 불가)                           (제한적 허용)
                 │                                     │
                 ▼                                     ▼
 [ 2. 1초 지각에 목숨이 날아가면 ]       [ 3. 지연된 데이터가 아무 짝에 쓸모없는가? ]
 [ 시스템 강제 셧다운 (하드 실시간) ]                 /             \
                                          (완전 쓰레기)       (아쉬운 대로 쓸만함)
                                                │                 │
                                                ▼                 ▼
                                    [ 쓰레기 결과 폐기 ]   [ 4. 화질 뭉개고 계속 재생 ]
                                      (펌 실시간)         (소프트 실시간)
```

### 동작 원리

1. 지각 삑사리 용서 불가 판정: **데드라인 미스** 발생 시 사람이 죽는지 기계가 부서지는지 치명성을 1차로 무자비하게 판정함.
2. 가차 없는 하드 실시간 분기: 1초 지각에 목숨이 날아가면 모든 걸 멈추고 **안전 상태**로 돌입해 시스템을 강제 차단함.
3. 늦은 쓰레기 데이터 가치 판정: 지연된 출력이 주식 호가처럼 1초만 늦어도 가치가 '0'이면 쳐다보지도 않고 **결과 폐기**함.
4. 잔여 가치 유튜브 버퍼링 확인: 늦게 도착해도 넷플릭스 영상처럼 화질(QoS)만 깎아서 계속 볼 수 있으면 소프트 실시간으로 구동함.

#### 한줄 요약

- 지각했을 때, 파국이면 하드(시스템 셧다운), 쓸모없어지면 펌(데이터 폐기), 렉 걸려도 괜찮으면 소프트(품질 저하)로 대응한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하드 실시간(Hard Real-Time)**: 브레이크 제어처럼 단 1번이라도 마감을 넘기면 사람이 닫히거나 기계가 박살 나는 끔찍하게 자비 없는 시스템이다.
- **펌 실 실시간(Firm Real-Time)**: 실시간 주식 호가처럼 늦게 온 데이터는 휴지 조각(가치 0)이라 버리지만, 버린다고 서버가 터지지는 않는 시스템이다.
- **소프트 실시간(Soft Real-Time)**: 게임 렉이나 유튜브 버퍼링처럼 늦으면 짜증은 나도 목숨엔 지장 없고, 데이터 가치가 천천히 떨어지는 널널한 시스템이다.

</details>

| 구분 | **하드 실시간** (Hard RT) | **펌 실시간** (Firm RT) | **소프트 실시간** (Soft RT) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 단 1번만 늦어도 사람 목숨이 날아가는 에어백, 미사일 궤도 제어처럼 자비 없는 완벽한 환경 | 늦어도 사람은 안 죽지만 늦은 데이터가 쓰레기가 되어 바로 버려야 하는 실시간 주식 틱 데이터 환경 | 좀 늦어도 짜증 날 뿐이지 목숨엔 지장 없는 유튜브 영상 버퍼링이나 롤(LoL) 게임 렉 환경 |
| 데드라인 삑사리 여파 | 규정 위반 및 끔찍한 연쇄 **시스템 실패** 참사 폭발 | 늦은 놈은 가차 없이 버리지만 시스템 자체는 안 뻗음 | 늦은 대로 대충 갖다 쓰며 전체 화질이나 품질(QoS)만 강하 |
| 마감 초과 시 데이터 가치 | 마이너스 수직 낙하(사람 죽고 회사 망하는 파국) | 딱 0 (아무 짝에도 쓸모없는 쓰레기 데이터 취급) | 0보다 큼 (가치는 떨어져도 눈곱만큼 쓸모는 있음) |

#### 한줄 요약

- 하드는 마감 어기면 파국, 펌은 마감 어기면 데이터 폐기, 소프트는 마감 어기면 퀄리티만 떨어지는 것으로 나뉜다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **안전 영향 분석(Safety Impact Analysis)**: 시스템 내 각 프로세스가 뻗었을 때 승객이 죽는지 다치는지 타박상인지(ASIL) 도메인 표준을 근거로 뼛속까지 캐는 평가이다.
- **장애 주입(Fault Injection)**: 진짜 고장 날 때까지 기다릴 수 없으니, 컴퓨터에 억지로 에러나 바이러스를 때려 넣어서 시스템이 방어(Fail-Safe)하는지 찌르는 테스트이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **하드 실시간** 태스크가 어쩌다 1번 지각했는데 차가 벽에 박아 운전자가 사망하는 대형 참사 발생 | 타이머가 절대 늦을 수 없음을 수학적으로 증명하고 뼛속까지 깐깐한 데드라인 충족을 무조건 사전 입증 | 어떠한 재수 없는 억까 상황에서도 제시간에 브레이크가 밟히는 절대 생존 보장 100% 확보 |
| **펌 실시간** 태스크가 이미 늦어 쓰레기가 된 데이터를 연산하느라 쓸데없이 CPU와 메모리 낭비 | 데드라인 미스 나는 순간 바로 멱살 잡고 태스크 킬 한 뒤 데이터 가차 없이 쓰레기통에 **결과 폐기** | 뻘짓하는 연산 자원을 1초 만에 즉시 회수하여 다음 타임슬롯 준비태세 쾌속 확립 |
| **소프트 실시간** 태스크 지연이 계속 쌓여서 넷플릭스 서버 전체가 메모리 부족으로 뻗어버리는 마비 | 프레임을 뚝뚝 끊어 버리거나 화질(QoS)을 144p로 박살 내버리는 다이내믹 품질 하향 스케일링 강제 | 고객이 욕은 좀 하더라도 서버가 터져서 뉴스에 나오는 서비스 전면 중단 굴욕 차단 |

#### 한줄 요약

- 하드는 절대로 늦지 않게 수학적으로 증명하고, 펌은 늦은 놈을 바로 쏴 죽이며, 소프트는 늦으면 화질을 낮춰서라도 서버 뻗는 걸 막아야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실시간 유형 선택(Real-Time Selection)**: 1초 지각했을 때 뉴스에 나올지, 주식이 휴지 조각이 될지, 고객센터에 클레임이 걸릴지 파급력을 따져 급을 나누는 체계이다.

</details>

- **실시간 유형 선택**에 따라 미스가 치명적이면 자비 없는 **하드**, 늦은 결과가 무효면 **펌**, 잔여 가치가 있으면 융통성 있는 **소프트** 판정을 단호히 결정함

#### 한줄 요약

- 사람이 죽으면 하드 실시간, 데이터가 쓰레기가 되면 펌 실시간, 렉이 걸리면 소프트 실시간으로 설계해라.
