## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 실시간 시스템에서 특정 태스크의 연산 결과가 유효성을 유지하기 위해 완수되어야 하는 엄격한 시간 한계.
- **효용 함수(Utility Function)**: 작업 완료 시점에 따라 시스템에 제공되는 가치(Value)나 유용성의 크기를 나타내는 수학적 모델.

</details>

- 정의/개념: 작업의 마감시간(Deadline) 위반 시 발생하는 **효용(Utility) 감소와 피해 심각도**에 따라 하드(Hard), 펌(Firm), 소프트(Soft)로 분류하는 실시간 시스템 체계
- 배경/필요성: 모든 지연을 같은 실패로 처리하면 안전 태스크는 보호하지 못하고 품질 태스크에는 과도한 자원 투입

#### 한줄 요약
- 늦으면 대형 사고가 나는지(Hard), 늦은 결과는 그냥 버리는지(Firm), 늦어도 조금은 쓸모가 있는지(Soft)로 나눈다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드 마감시간(Hard Deadline)**: 마감시간 위반을 허용하지 않아 설계 단계에서 최악 응답시간 충족을 입증해야 하는 시간 제약.
- **QoS 저하(Graceful Degradation)**: 소프트 실시간 환경에서 지연 발생 시 서비스가 중단되는 대신 화질 저하 등으로 품질을 점진적으로 낮추는 기법.

</details>

- **하드(Hard)**: 마감시간 위반을 허용하지 않으며 안전 기능은 위반 시 위험 상태로 전이 가능
- **펌(Firm)**: 마감시간을 넘긴 결과의 효용 가치는 0이 되어 즉시 폐기되나 시스템 파국은 없음
- **소프트(Soft)**: 마감시간 초과 후에도 지연된 결과가 유효하며 시스템 효용이 완만하게 감소

#### 한줄 요약
- 하드는 마감시간 미스 시 재앙, 펌은 무가치 폐기, 소프트는 서비스 품질 저하로 이어진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **효용 곡선(Time-Utility Curve)**: 시간 경과에 따른 가치 변화를 시각화한 그래프로, Hard는 음의 무한대, Firm은 0으로 수직 낙하, Soft는 점진 감쇄 곡선을 가짐.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 마감시간(Deadline, D) 경과에 따른 효용(Utility) 곡선       │
│                                                             │
│  효용 (Utility)                                             │
│   ▲                                                         │
│ 1 ├───┐                                                     │
│   │   │                                                     │
│   │   │                                                     │
│ 0 └───┴───────────────────────► 시간 (Time)                 │
│      [D]                                                    │
│       │                                                     │
│       ├─► [Soft RT] : 완만한 효용 감쇄 (동영상 스트리밍)    │
│       ├─► [Firm RT] : 효용 0으로 즉시 추락 (금융 시세/추적) │
│       └─► [Hard RT] : 음의 무한대(재앙적 손실, 에어백/원전) │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 마감시간(D)을 기준으로 시스템의 효용 가치가 각각 음의 무한대(Hard), 0(Firm), 점진 감소(Soft)로 분기

| 구성요소 | 책임 |
|:---|:---|
| 하드 실시간 (Hard RT) | WCET·블로킹·간섭을 포함한 최악 응답시간이 마감시간 이내임을 입증 |
| 펌 실시간 (Firm RT) | 마감 초과 텐서/프레임을 즉시 드롭(Drop)하고 최신 데이터 획득 우선 실행 |
| 소프트 실시간 (Soft RT) | 버퍼링 및 적응형 품질 제어(QoS)로 사용자 체감 지연 최소화 유지 |
| 실시간 감시 타이머 | 각 태스크의 시작/종료 시각을 계측하고 마감 위반 시 폴백 루틴 기동 |
| 안전 상태 전환기 (Failsafe) | Hard RT 마감시간 미스 감지 시 시스템을 사전에 정의된 안전 정지 모드로 전환 |

#### 한줄 요약
- Hard(결함 불허), Firm(지연 데이터 즉시 폐기), Soft(품질 저하 수용), 안전 Failsafe 모듈이 조화를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **폴백(Fallback)**: 제어 연산 마감시간 초과 시 이전 안전 제어값을 재사용하거나 기본값으로 전환하는 비상 기법.

</details>

```text
외부 이벤트 및 센서 데이터 수신
      │
      ▼
1. 도메인 속성 분류
      │
      ▼
2. 선점형 디스패치
      │
      ▼
3. 완료 시점 체크
      ├── [YES] ──► 정상 출력 및 액추에이터 구동
      └── [NO]  ──► 4. 차등적 예외 처리
                     ├─ Hard RT : 즉각 안전 정지(Safe Stop) 또는 긴급 롤백
                     ├─ Firm RT : 지연된 연산 결과 폐기(Drop) 및 최신 주기 대기
                     └─ Soft RT : 지연 결과 수용 및 QoS 버퍼링 보정
                                      │
                                      ▼
                              5. 통계 및 튜닝
```

**동작 원리**

1. **도메인 속성 분류**: 태스크 생성 시 마감시간, 주기, 실패 시 심각도를 기반으로 범주 부여
2. **선점형 디스패치**: 주기·마감시간·간섭 분석 결과에 따라 우선순위 또는 기한 기반 실행
3. **완료 시점 체크**: 하드웨어 타이머와 비교하여 마감시간 초과 여부를 즉시 판별
4. **차등적 예외 처리**: Hard는 Failsafe 정지, Firm은 버퍼 폐기, Soft는 지연 출력으로 분기
5. **통계 및 튜닝**: 마감시간 미스 빈도를 로깅하여 스케줄러 우선순위 및 WCET 재조정

#### 한줄 요약
- 이벤트 수신 → 속성 분류 → 스케줄링 → 마감시간 검사 → 범주별 차등 예외 처리 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 실시간 시스템 범주 | 하드 실시간 (Hard RT) | 펌 실시간 (Firm RT) | 소프트 실시간 (Soft RT) | 비실시간 (Non RT) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 차량 ABS, 에어백, 원전 제어, 항공 항법 | 초단타 주식 거래, 레이더 타깃 추적 | 동영상 스트리밍, 온라인 게임, 웹 서버 | 배치 데이터 분석, 컴파일러, 문서 편집 |
| 핵심 특징 | 마감시간 미스 시 시스템 전체 붕괴 및 인명 사고 | 마감 초과 결과는 효용 0 (즉시 폐기) | 마감 초과 시 품질 저하(QoS), 동작 유지 | 마감시간 개념 부재, 총 처리량(Throughput) 중심 |
| 한계 | WCET 입증 및 정적 분석 난이도 극상 | 잦은 데이터 드롭 시 제어 연속성 저하 | 사용자 경험(UX) 불만족 및 지연 누적 | 응답 시간 예측 불가 및 실시간 제어 불가 |

#### 한줄 요약
- 절대 안전은 Hard, 최신성 유지는 Firm, 체감 품질은 Soft, 대량 일괄 처리는 Non-RT를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **지터(Jitter)**: 주기적 태스크의 실행 시작 또는 완료 시각이 기준 주기에서 벗어나는 시간적 변동 편차.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Hard RT 태스크의 **최악 응답시간 초과** | WCET·블로킹·인터럽트 간섭을 포함한 응답시간 분석 | 마감시간 미충족 경로를 배포 전에 식별 |
| Firm RT 영상 처리에서 **연쇄적 프레임 지연 및 버퍼 오버플로우** | 지연 프레임 즉시 드롭(Frame Dropping) 및 최신 I-프레임 동기화 | 최신성 복원 및 큐 지연 해소 |
| Soft RT 스트리밍에서 **네트워크 지연으로 인한 화면 끊김(버퍼링)** | 적응형 비트레이트(ABR) 및 동적 클라이언트 버퍼링 확대 | 연속 재생성 유지 및 UX 개선 |
| Hard·Soft 혼재 시 **공유 자원 간섭** | 시간·메모리·I/O 대역폭 예약과 우선순위 상한 적용 | 안전 태스크의 간섭 상한과 Soft 예산 분리 |

#### 한줄 요약
- 캐시 락으로 Hard의 WCET를 지키고, 프레임 드롭으로 Firm을 수습하며, ABR로 Soft의 품질을 타협한다.

## Ⅶ. 결론

- 마감 위반이 안전 실패면 **Hard RT**, 늦은 결과가 무가치하면 Firm, 품질만 감소하면 Soft 적용
- 분류명만으로 보장하지 말고 최악 응답시간·오버런 대책·안전 상태까지 함께 검증

#### 한줄 요약
- 마감시간 위반 시의 효용 감소 특성을 시스템 설계 초기부터 명확히 정의하여 차등적 스케줄링과 안전 대책을 수립해야 한다.
