## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **피시에이아이(Peripheral Component Interconnect Express, PCIe)**: 그래픽카드나 SSD를 메인보드에 꽂을 때 쓰는 초고속 직렬 통신 규격으로, 데이터를 차선(레인) 단위로 쏴버리는 컴퓨터의 핵심 척추이다.
- **PCIe 스위치(PCIe Switch)**: 멀티탭 하나에 플러그 여러 개 꽂듯이, 부족한 CPU PCIe 구멍 하나를 문어발처럼 늘려주는 영리한 분배기 칩셋이다.
- **스위칭 패브릭(Switching Fabric)**: 스위치 안에서 택배(데이터) 목적지를 까보고 "넌 1번 GPU로 가, 넌 2번 SSD로 가!" 하고 길을 찾아주는 핵심 우체국 로직이다.

</details>

- 정의: 단일 루트 컴플렉스(Root Complex) 하단에서 복수의 PCIe 엔드포인트를 확충하고 P2P(Peer-to-Peer) 트랜잭션을 디스패치하는 **PCIe 스위치** 아키텍처
- 배경: CPU에 직접 꽂을 수 있는 구멍(레인)이 턱없이 부족하고, 그래픽카드(GPU)와 SSD끼리 CPU를 안 거치고 데이터를 직거래(P2P) 해야 하는 미친 대역폭 요구성을 감당하기 위함

#### 한줄 요약

- 부족한 CPU 꽂기 구멍을 문어발처럼 늘려주고, 부품들끼리 CPU 안 거치고 다이렉트로 통신하게 해주는 칩셋이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **티엘피(Transaction Layer Packet, TLP)**: PCIe 고속도로 위를 달리는 진짜 택배 상자로, "데이터 읽어라, 써라" 하는 명령과 주소가 담겨 있다.
- **피투피 전송(Peer-to-Peer Transfer)**: 멍청하게 CPU한테 허락받으러 안 가고, GPU랑 SSD끼리 스위치 안에서 다이렉트로 데이터를 직거래하는 상남자식 전송이다.
- **접근 제어 서비스(Access Control Services, ACS)**: 직거래(P2P)한다고 남의 메모리까지 막 쑤시고 다니지 못하게, 멱살 잡고 통행증 검사하는 보안 검색대이다.
- **초과 구독(Oversubscription)**: 밑에 달린 부품 10개가 10GB씩 쏘는데, 위로 올라가는 본선 도로는 50GB밖에 안 돼서 꽉 막혀버리는 대환장 병목 사태이다.

</details>

![PCIe 스위치 본선 부하율에 따른 대기 지연 차트](/study/diagrams/pcie-oversubscription-delay.svg)

- CPU나 시스템 램(호스트 메모리)을 전혀 안 거치고, GPU와 SSD끼리 다이렉트로 데이터를 쏴버리는 초고속 **피투피 전송**을 지원함.
- 밑에 달린 장비들이 한 번에 데이터를 쏘면 윗선(업스트림) 대역폭이 모자라 지연이 터지는 **초과 구독** 사태를 멱살 잡고 관리함.
- 아무 놈이나 P2P로 남의 메모리를 쑤시지 못하도록 **접근 제어 서비스**(ACS)와 IOMMU를 엮어서 트랜잭션을 철저히 격리 통제함.

$$
\rho = \frac{\sum_{i=1}^{N} B_{i,\mathrm{demand}}}{B_{\mathrm{up,usable}}}
$$

#### 한줄 요약

- CPU 안 거치고 자기들끼리 직거래(P2P)하게 해주는데, 한꺼번에 쏘면 본선이 막히니까 멱살 잡고 보안과 교통정리를 해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트 컴플렉스(Root Complex)**: CPU와 램(메모리)이 떡하니 버티고 있는 절대 권력의 본진이자, 모든 PCIe 도로망의 대가리이다.
- **업스트림 포트(Upstream Port)**: 스위치 입장에서 대가리(루트) 쪽을 향해 뚫려 있는 윗방향 톨게이트이다.
- **다운스트림 포트(Downstream Port)**: 밑에 달린 말단 장비(GPU, SSD) 쪽으로 뚫려 있는 아랫방향 톨게이트이다.

</details>

```text
[ PCIe 스위치 문어발 확장 및 직거래(P2P) 프레임워크 ]
                          [ 루트 컴플렉스 (절대 본진) ]
                                      │
                         [ 업스트림 포트 (윗선 입구) ]
                                      │
                         [ 스위칭 패브릭 (길찾기 우체국) ]
                                /             \
            [ 다운스트림 포트 (출구 1) ]   [ 다운스트림 포트 (출구 2) ]
                        │                             │
              [ 엔드포인트 (GPU 1) ]        [ 엔드포인트 (SSD 1) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **루트 컴플렉스** | CPU와 메모리가 있는 본진으로, 전체 PCIe 고속도로망을 통제하는 절대 권력의 최상위 노드 |
| **업스트림 포트** | 본진(루트) 쪽을 향해 뚫려 있는 스위치의 윗방향 포트로, 트랜잭션(**TLP**)을 빨아들이는 입구 |
| 스위칭 패브릭 | 들어온 TLP의 주소표를 까보고 "넌 본진으로 가라", "넌 GPU로 가라" 하고 냅다 던져버리는 라우팅 코어 |
| **다운스트림 포트** | GPU, NVMe SSD 같은 실제 장비(엔드포인트)들과 물리적인 선(레인)으로 묶여있는 아랫방향 출구 포트 |
| 엔드포인트 | 실제로 계산하거나 데이터를 저장하는 말단 노가다 장비들로, 명령을 던지거나 응답을 뱉어냄 |

#### 한줄 요약

- 본진(루트)에서 업스트림으로 내려온 패킷을, 패브릭이 주소를 보고 다운스트림의 장비(엔드포인트)로 던져준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **요청자 아이디 앤 태그(Requester ID & Tag)**: 택배 보내는 놈 이름(ID)과 운송장 번호(Tag)를 적어둬서, 나중에 반품(응답) 올 때 안 헷갈리게 하는 장부이다.
- **크레딧 기반 흐름 제어(Credit-Based Flow Control)**: 받는 쪽 버퍼(창고)가 꽉 찼는지 안 찼는지 미리 포인트(크레딧)를 주고받아서, 박스 터지는 참사를 막는 지능적인 속도 조절이다.

</details>

```text
[ 피시에이아이 트랜잭션 라우팅 및 직거래 피투피 십자포화 흐름 ]
                                 │
                                 ▼
   [ 1. 접수 및 장부 기록: 스위치가 택배(TLP)를 받고 운송장 번호(Tag) 적어둠 ]
                                 │
                                 ▼
    [ 2. 멱살 라우팅: 주소표 까보고 본진 보낼지 다른 놈한테 직거래(P2P) 보낼지 결정 ]
                                 │
               ┌─────────────────┴─────────────────┐
               ▼                                   ▼
        ( 본진 방향 )                         ( P2P 직거래 방향 )
    [ 루트 컴플렉스 등판 ]            [ 3. 보안 검색: ACS랑 IOMMU로 권한 검사 ]
               │                                   │
               └─────────────────┬─────────────────┘
                                 ▼
    [ 4. 작업 및 반환: 대상 장비가 일 처리하고 아까 적어둔 운송장 보고 원래 놈한테 반환 ]
```

### 동작 원리

1. 포트 수신 및 태그 추적: 스위치가 택배(**TLP**)를 받으면 누가 보냈는지(Requester ID)랑 꼬리표(Tag)를 장부에 꼼꼼히 적어둠.
2. 주소 디코딩 및 길 안내: 스위칭 패브릭이 택배 주소를 까보고 본진으로 보낼지, 다른 장비로 직거래(**피투피 전송**) 보낼지 냅다 던짐.
3. 멱살 검증 및 보안 격리: 아무나 쑤시지 못하게 **접근 제어 서비스**(ACS)와 **IOMMU**로 DMA 주소 접근 권한을 얄짤없이 검사함.
4. 완료 처리 및 택배 반환: 대상 장비가 명령을 수행한 뒤, 아까 적어둔 꼬리표를 보고 원상 복귀하는 완료 TLP를 반환함.

#### 한줄 요약

- 택배(TLP)가 오면 장부에 적어놓고 보안 검사 빡세게 돌린 뒤 던져주고, 일 끝나면 원래 보낸 놈한테 다시 돌려준다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 연결(Direct Attachment)**: 스위치 같은 거북한 중간 브로커 다 빼고, CPU 핀에다가 장비를 1:1로 다이렉트로 꽂아버리는 상남자식 다이렉트 연결이다.

</details>

| 비교 항목 | **PCIe 스위칭** (Switching Topology) | **직접 연결** (Direct Attachment) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | AI 서버처럼 GPU 8개, SSD 10개씩 무식하게 때려 박고 지들끼리 직거래(P2P) 해야 할 시 | CPU에 꽂을 장비가 몇 개 안 돼서, 스위치 딜레이 없이 다이렉트로 빛의 속도로 꽂아야 할 시 |
| 아키텍처 핵심 구현 특징 | 하나의 선(업스트림)을 스위치로 쪼개서 수십 개의 장비를 문어발처럼 거느리고 자기들끼리 직거래 통로 뚫어줌 | 스위치 따위 안 거치고 CPU 직결 레인에 다이렉트로 꽂아서 나 혼자 CPU 대역폭 100% 독식함 |
| 극복해야 할 태생적 한계점 | 아랫놈들이 동시에 데이터 쏘면 윗선(업스트림) 대역폭이 꽉 막히는 **초과 구독** 병목 터짐 | CPU가 제공하는 PCIe 레인 수가 모자라면 더 이상 장비를 꽂을 구멍이 아예 없음 |

#### 한줄 요약

- 부품 수십 개를 문어발로 달고 직거래(P2P)하려면 스위치를 쓰고, 소수 정예로 스위치 딜레이 없이 쓰려면 다이렉트로 꽂아라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **다운트레이닝(Downtraining)**: 선로에 노이즈가 너무 심해서 "야, 이 속도로는 에러 터져!" 하고 기계가 쫄아서 스스로 속도나 차선(레인)을 반토막 내버리는 굴욕이다.
- **아이오엠엠유(Input-Output MMU, IOMMU)**: 가상 머신(VM)이나 P2P 할 때 남의 구역 침범 못 하게 메모리 주소를 멱살 잡고 통제하는 깡패 하드웨어이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 밑에 달린 GPU들이 동시에 미친 듯이 데이터를 쏴서 업스트림 본선이 꽉 막혀버리는 **초과 구독** 재앙 터짐 | 최대 부하량을 계산해 업스트림 용량을 넉넉하게 뚫고 뼈 깎는 대역폭 트래픽 제어(QoS) 강력 도입 | 패브릭이 막혀서 시스템이 뻗어버리는 병목 현상과 꼬리 지연을 멱살 잡고 완화시킴 |
| 선로 노이즈가 심해서 최고 속도(Gen5)로 못 달리고, 강제로 속도가 반토막 나는 **다운트레이닝** 발생 | 중간중간에 신호 증폭기(리타이머)를 떡칠하고 신호 무결성(SI/PI) 빡세게 시뮬레이션 돌림 | 속도 반토막 나는 굴욕 없이 목표로 한 PCIe 레인 폭과 세대(Gen) 최고 성능 절대 사수 |
| GPU가 남의 메모리나 다른 가상 머신(VM) 영역을 허락도 없이 쑤셔버리는 악성 P2P 해킹 공격 발발 | 스위치에서 **ACS** 기능을 강제 활성화하고 **아이오엠엠유**(IOMMU)로 가상 주소 멱살 잡아 완벽 격리 | 가상 머신 간 불법 DMA 데이터 탈취 공격을 철저히 차단해 극강의 보안 아키텍처 완성 |

#### 한줄 요약

- 본선 안 막히게 용량 넉넉히 뚫고, 신호 안 깎이게 증폭기 달고, 남의 메모리 못 쑤시게 IOMMU랑 ACS로 틀어막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PCIe 선택 기준(PCIe Architecture Selection Criteria)**: 장비를 몇 개나 꽂을 건지, 직거래(P2P)가 필요한지, 본선이 막힐지(초과 구독) 계산해서 스위치를 달지 말지 결정하는 기준표이다.

</details>

- **PCIe 선택 기준** 원칙에 따라, 다수 장치 및 P2P 직거래 필수 시 **PCIe 스위칭** 적용, 소수 장치 및 딜레이 최소화 시 **직접 연결** 채택 기조 확립함

#### 한줄 요약

- 장비 많이 박고 자기들끼리 직거래해야 하면 PCIe 스위치를 달고, 장비 적고 지연 없이 쓸 거면 직결해라.
