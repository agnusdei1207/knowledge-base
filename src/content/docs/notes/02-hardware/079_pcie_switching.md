## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **PCI 익스프레스(Peripheral Component Interconnect Express, PCIe)**: 직렬 점대점 링크로 프로세서와 주변장치를 연결하는 고속 인터커넥트이다.
- **PCIe 스위치(PCIe Switch)**: 하나의 업스트림 링크를 여러 다운스트림 포트로 분기하고 TLP를 라우팅하는 장치이다.
- **패브릭(Fabric)**: 여러 포트 사이에서 패킷의 목적지 경로와 전송 순서를 결정하는 내부 연결망이다.

</details>

- 정의/개념: 하나 이상의 업스트림 경로와 여러 다운스트림 포트 사이에서 PCIe TLP를 주소에 따라 전달하는 **PCIe 스위치**와 내부 **패브릭** 구조이다.
- 배경/필요성: 모든 장치를 루트 포트에 직접 연결하면 포트 수와 배선 확장에 한계가 있고 장치 간 P2P 경로 구성도 제약된다.

#### 한줄 요약

- PCIe 스위치는 루트 측 링크 아래에 여러 엔드포인트와 P2P 경로를 확장하는 패킷 패브릭이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **흐름 제어 크레딧(Flow-control Credit)**: 수신 버퍼가 받아들일 수 있는 패킷 양을 송신 측에 알리는 값이다.
- **트래픽 등급(Traffic Class)**: PCIe 패킷의 우선순위와 서비스 정책을 구분하는 속성이다.
- **오버서브스크립션(Oversubscription)**: 여러 하위 장치의 동시 요구 대역폭 합이 공유 업스트림 용량을 넘는 상태이다.
- **꼬리 지연(Tail Latency)**: 지연 분포의 높은 백분위에서 나타나는 가장 느린 요청들의 지연이다.
- **M/M/1 대기행렬(Markovian/Markovian/One-server Queue)**: 지수 분포 도착•서비스와 단일 서버를 가정한 대기 모형이다.

</details>

![PCIe 스위치 본선 부하율에 따른 대기 지연 차트](/study/diagrams/pcie-oversubscription-delay.svg)

> 요약: **M/M/1 대기행렬**의 부하율이 1에 가까워질수록 대기 지연이 급증한다.

- **흐름 제어 크레딧**으로 수신 버퍼 범위에서 송신량을 제한한다.
- **트래픽 등급**에 따른 중재로 우선순위별 패브릭 경로를 할당한다.
- **오버서브스크립션** 시 업스트림 대기와 **꼬리 지연**이 증가한다.

#### 한줄 요약

- 갈래마다 흐름을 따로 조절해도 장치 요구량 합이 본선 용량을 넘으면 대기한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **루트 컴플렉스(Root Complex)**: 중앙 처리 장치와 메모리 시스템을 PCIe 장치 계층에 연결하는 시작점이다.
- **업스트림 포트(Upstream Port)**: PCIe 스위치에서 루트 컴플렉스 방향의 링크에 연결되는 포트이다.
- **스위칭 패브릭(Switching Fabric)**: 목적지 주소와 중재 결과에 따라 TLP의 출력 포트를 선택하는 내부 연결망이다.
- **다운스트림 포트(Downstream Port)**: PCIe 스위치에서 엔드포인트나 하위 스위치 방향 링크를 제공하는 포트이다.
- **엔드포인트(Endpoint)**: PCIe 계층 끝에서 메모리•입출력 요청을 발행하거나 처리하는 장치이다.

</details>

```text
루트 컴플렉스
└─ 업스트림 포트
   └─ 스위칭 패브릭
      ├─ 다운스트림 포트
      │  └─ 엔드포인트
      └─ … 동일 포트•엔드포인트 반복
```

가지의 의미: 스위칭 패브릭이 여러 다운스트림 링크를 분기하는 정적 포트 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 루트 컴플렉스 | CPU•메모리 계층 연결 |
| 업스트림 포트 | 루트 링크 연결 |
| 스위칭 패브릭 | 출력 선택•중재 |
| 다운스트림 포트 | 장치별 링크 제공 |
| 엔드포인트 | 요청 발행•완료 처리 |

#### 한줄 요약

- **루트 컴플렉스·업스트림 포트·스위칭 패브릭·다운스트림 포트·엔드포인트**를 계층형 PCIe로 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **트랜잭션 계층 패킷(Transaction Layer Packet, TLP)**: 메모리와 입출력 요청, 데이터 및 완료 정보를 전달하는 PCIe 패킷이다.
- **요청자(Requester)**: 요청 TLP를 발행하는 장치이다.
- **완료자(Completer)**: 요청을 처리하여 완료 TLP를 반환하는 장치이다.
- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: 장치의 DMA 주소를 변환하고 메모리 접근 범위를 제한하는 하드웨어이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치가 중앙 처리 장치를 거치지 않고 메모리에 직접 접근하는 방식이다.
- **업스트림 오버서브스크립션 비율**: 하위 장치의 동시 요구 대역폭 합을 공유 업스트림 유효 대역폭으로 나눈 값이다.
- **포트 수신·거래 식별**: 요청 TLP의 주소와 요청자 ID 및 태그를 읽는 단계이다.
- **주소 디코딩·중재**: 주소와 라우팅 규칙으로 출력 포트와 사용 순서를 정하는 단계이다.
- **경로·접근 통제**: ACS와 IOMMU로 P2P 및 DMA 접근 범위를 검증하는 단계이다.
- **완료자 처리·응답 반환**: 요청을 처리한 뒤 완료 TLP를 원 요청자에게 돌려주는 단계이다.

</details>

```text
[요청 엔드포인트의 요청 TLP]
              │
              ▼
1. 포트 수신•태그 추적
              │
              ▼
2. 주소 디코딩•중재
              │
       ┌──────┴────────┐
       │ 루트 방향     │ P2P 방향
       ▼               ▼
[루트 컴플렉스]   [대상 엔드포인트]
       └──────┬────────┘
              ▼
3. 접근 경계 검증
              │
              ▼
4. 완료자 요청 처리
              │
              ▼
[완료 TLP를 원 요청자에 반환]
```

### 업스트림 오버서브스크립션 비율 산식

$$
\rho = \frac{\sum_{i=1}^{N} B_{i,\mathrm{demand}}}{B_{\mathrm{up,usable}}}
$$

> 요약: **업스트림 오버서브스크립션 비율**이 1을 넘으면 중재 대기가 발생한다.

### 동작 원리

1. **포트 수신•거래 식별**: 스위치가 요청 TLP의 주소와 요청자 ID 및 태그를 읽어 전달 정보를 확인한다.
2. **주소 디코딩•중재**: 주소와 라우팅 규칙으로 업스트림 또는 P2P 출력 포트를 고르고 공유 패브릭 사용 순서를 정한다.
3. **경로•접근 통제**: ACS는 P2P 전달 또는 업스트림 리디렉션을 통제하고, 루트 측 IOMMU는 DMA 주소와 메모리 권한을 검증한다.
4. **완료자 처리•응답 반환**: 메모리나 엔드포인트가 요청을 처리하고, 읽기•비게시 요청의 완료 TLP를 요청자 ID와 태그에 따라 반환한다.

#### 한줄 요약

- 요청을 **완료자**에게 보내고 **요청자** ID•태그로 완료 **TLP**를 원 요청자에게 반환한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **동료 간 통신(Peer-to-peer, P2P)**: 두 PCIe 엔드포인트가 호스트 메모리를 경유하지 않고 스위치 경로로 직접 통신하는 방식이다.
- **직접 연결(Direct Attachment)**: 각 엔드포인트를 별도의 루트 포트에 일대일로 연결하는 구조이다.
- **전용 대역폭(Dedicated Bandwidth)**: 다른 장치와 업스트림 링크를 공유하지 않아 한 장치가 독점적으로 사용할 수 있는 용량이다.

</details>

| 연결 아키텍처 | PCIe 스위칭 | 직접 연결 |
|:---|:---|:---|
| 적용 기준 | 장치 확장•**P2P** 경로 필요 | 적은 장치에 **전용 대역폭** 우선 |
| 핵심 특징 | PCIe 스위칭의 업스트림 공유•분기 | **직접 연결**의 루트 포트 1:1 구성 |
| 한계 | 공유 본선•중재 지연 | 루트 포트 소모 |

#### 한줄 요약

- 스위치는 **장치 확장•P2P 경로**에 유리하고, 직접 연결은 장치별 전용 업링크 대역폭에 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **링크 폭(Link Width)**: x1•x4•x8처럼 링크를 구성하는 레인 수와 총 병렬 전송 용량을 나타내는 속성이다.
- **홉(Hop)**: 패킷이 목적지까지 이동하면서 통과하는 PCIe 스위치 한 단계이다.
- **접근 제어 서비스(Access Control Services, ACS)**: P2P 요청의 허용과 업스트림 리디렉션을 제어하는 PCIe 보안 기능이다.
- **다운트레이닝(Downtraining)**: 링크 협상 결과가 목표보다 낮은 속도나 레인 수로 동작하는 현상이다.
- **가상 머신(Virtual Machine, VM)**: 물리 컴퓨터의 자원을 분리하여 실행하는 가상 컴퓨터 환경이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동시 요구량 합이 업스트림 유효 대역폭 초과 | 동시 부하와 **링크 폭** 산정 | 본선 병목 완화 |
| 스위치 **홉**과 중재 대기가 누적돼 꼬리 지연 증가 | 홉 최소화•중재 지연 계측 | 꼬리 지연 감소 |
| P2P DMA가 IOMMU를 거치지 않아 **VM** 격리 약화 | **ACS** 리디렉션과 IOMMU 정책 검증 | 장치•VM 격리 유지 |
| 협상 오류로 목표보다 낮은 링크 폭•속도로 동작 | 링크 상태•오류 수 감시 | **다운트레이닝** 탐지 |

#### 한줄 요약

- 가속기를 배치할 때 P2P 경로와 업스트림 용량 및 스위치 홉을 함께 산정해야 병목과 꼬리 지연을 예측할 수 있다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **장치 확장(Device Expansion)**: 제한된 루트 포트 아래에 더 많은 PCIe 엔드포인트를 연결하는 요구이다.
- **업스트림 용량(Upstream Capacity)**: 스위치의 모든 하위 트래픽이 루트 방향으로 공유하는 링크의 유효 대역폭이다.
- **접근 경계(Access Boundary)**: 장치와 가상 머신이 DMA로 접근할 수 있는 메모리와 P2P 대상의 범위이다.
- **PCIe 연결 아키텍처 선택 기준**: 장치 확장과 P2P 요구 및 업스트림 용량·접근 경계로 스위칭과 직접 연결을 고르는 기준이다.

</details>

- **PCIe 연결 아키텍처 선택 기준**에 따라 **장치 확장**과 P2P가 필요하고 **업스트림 용량**이 충분하며 **접근 경계**를 통제할 수 있으면 PCIe 스위칭을 선택한다.

#### 한줄 요약

- 장치 확장과 P2P가 필요하면 공유 업스트림 용량과 ACS•IOMMU 접근 경계를 함께 설계한다.
