## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 매핑(Cache Mapping)**: 메인 메모리(DRAM)의 물리적 데이터 블록을 고속 캐시 메모리(SRAM)의 특정 라인 위치에 배치하고 적중 여부를 판단하기 위한 주소 변환 알고리즘.
- **캐시 라인(Cache Line / Block)**: 메인 메모리와 캐시 메모리 간 데이터 전송 및 일관성 관리의 기본 블록 단위(일반적으로 64-Byte).
- **태그 비교(Tag Comparison)**: CPU가 요청한 메모리 주소의 Tag 필드와 캐시 라인 태그 메모리에 보관된 비트를 비교기(Comparator) 회로로 대조하여 Cache Hit/Miss를 판정하는 작동.
- **메모리 벽(Memory Wall)**: CPU 연산 속도 향상률 대비 메인 메모리(DRAM)의 접근 속도 지연 격차가 벌어져 전체 처리 성능이 저하되는 현상.
- **충돌 미스(Conflict Miss)**: 서로 다른 메모리 블록이 동일한 캐시 슬롯(Index)으로 동시에 매핑되어 기존 유효 라인을 축출하며 발생하는 캐시 미스.

</details>

- 정의: 주소를 분해하여 특정 집합(Set)을 찾고 **태그 비교**로 적중을 판정하는 **캐시 매핑** 알고리즘
- 배경: 메인 메모리 지연과 주소 쏠림으로 인한 **메모리 벽** 및 **충돌 미스** 발생

#### 한줄 요약
- Index로 캐시 집합 선택, Tag 비교로 Hit/Miss 판정하는 주소 매핑 구조

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **연관도(Associativity)**: 하나의 메인 메모리 블록이 적재될 수 있는 후보 캐시 라인(Set 내의 Way)의 개수.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: 적중 시간과 미스 비율, 미스 페널티의 곱으로 계산되는 전체 메모리 참조 지연 지표.
- **충돌 미스(Conflict Miss)**: 동일한 캐시 집합(Set)으로 인덱싱되는 주소가 몰려, 빈 슬롯이 남아있음에도 특정 위치 쫓겨남이 반복되는 미스 현상.
- **웨이(Way)**: 1개 캐시 집합(Set) 내부에서 데이터를 병렬 적재할 수 있는 독립된 캐시 라인 슬롯.
- **적중 시간(Hit Time, $T_{hit}$)**: 캐시 메모리에서 태그를 비교하고 최상위 억세스 데이터를 ALU로 인출하기까지의 시간.
- **미스율(Miss Rate)**: 전체 메모리 요청 중 캐시 적중에 실패하여 하위 캐시나 메인 메모리로 억세스하는 비율.
- **미스 페널티(Miss Penalty)**: 캐시 미스 발생 시 DRAM 메인 메모리로부터 64바이트 라인을 인출해 올 때 소비되는 지연 클록 수.

</details>

- **연관도** 증가 시 지정 집합 내 분산 배치로 **충돌 미스** 대폭 감소
- 연관도 상향 시 태그 비교기 증가로 **적중 시간** 트레이드오프 발생
- **적중 시간**•**미스율**•**미스 페널티**로 전체 **AMAT** 산출

$$
AMAT = T_{hit} + (Miss\ Rate \times Miss\ Penalty)
$$

#### 한줄 요약

- **연관도** 상향으로 충돌 미스를 억제하며, **AMAT**를 기준으로 적중 시간과 절충한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **태그(Tag)**: 메모리 주소 상위 비트로 구성되어, 캐시 라인에 들어있는 데이터가 어떤 메인 메모리 블록에서 온 것인지를 정밀 검증하는 식별자.
- **인덱스(Index)**: 메모리 주소 중간 비트로 구성되어, 접근할 캐시 집합(Set) 번호를 다중화 디코더로 선택하는 인덱스 비트.
- **오프셋(Offset)**: 메모리 주소 하위 비트로 구성되어, 64바이트 캐시 라인 블록 내부에서 원하는 1/2/4/8 바이트 데이터를 지시하는 포인터.
- **유효 비트(Valid Bit)**: 해당 캐시 라인에 적재된 데이터가 쓰레기 값이 아닌 유효한 전원/메모리 데이터인지를 지시하는 1비트 상태 플래그.
- **교체 정책(Replacement Policy)**: 모든 Way가 가득 찬 집합에 새 블록을 적재할 때 기존 캐시 라인을 쫓아내는 축출 알고리즘이다.
- **LRU(Least Recently Used)**: 가장 오랫동안 참조되지 않은 캐시 라인을 우선 축출하는 교체 정책이다.
- **태그 탐색부(Tag Lookup Unit)**: N-Way 파이프라인 비교기들을 통해 선택된 집합 내부의 N개 태그를 동시 병렬 대조하는 로직이다.
- **데이터 배열(Data Array)**: 실제 64바이트 데이터 블록 사본을 보유하고 적중 시 억세스 딜리버리를 구동하는 배열이다.

</details>

```text
+--------------------------------------------------------------+
|              Physical Memory Address                         |
| +------------------+----------------+------------------+     |
| |  Tag (20-bit)    | Index (6-bit)  |  Offset (6-bit)  |     |
| +------------------+----------------+------------------+     |
+--------------------------------------------------------------+
          │                  │                  │
          │     +------------+------------+     │
          │     | Set Decoder              |     │
          │     +---+----+----+----+------+     │
          │         │    │    │    │             │
          │     +---+----+----+----+------+     │
          │     | N-Way Tag Comparators   |     │
          │     +------------------------+     │
          │                                    │
          │     +------------------------+     │
          │     | Data Array MUX         |-----+
          │     +------------------------+
          │
+-------------------+
| Valid Bit Storage |
+-------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| 주소 분해기 | CPU 주소를 **태그**•**인덱스**•**오프셋** 비트로 파싱 |
| 태그 탐색부 | N-Way 병렬 비교기로 **캐시 적중** 여부 판정 |
| 데이터 배열 | 적중한 Way의 **오프셋** 위치 데이터 반환 |
| 교체 제어부 | 집합 포화 시 **LRU** 기반 기존 라인 축출 |

#### 한줄 요약

- 주소를 분해하여 인덱스로 집합을 찾고, 태그를 비교해 캐시 적중 여부를 판정한 뒤 데이터를 반환하거나 LRU로 축출한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 적중(Cache Hit)**: 요청한 메인 메모리 블록이 이미 캐시 메모리 상의 유효한 라인에 존재하여 SRAM에서 지연 없이 데이터를 읽어오는 상태이다.
- **캐시 미스(Cache Miss)**: 요청 블록이 캐시에 없어 하위 캐시 계층이나 메모리에서 가져와야 하는 상태이다.
- **축출(Eviction)**: 미스 발생 시 교체 정책(LRU)에 의해 선택된 희생 캐시 라인을 비우는 동작이다.
- **리필(Refill)**: 하위 메모리 계층에서 읽어온 신규 블록을 비워진 캐시 라인에 채우는 작업이다.

</details>

```text
 CPU Request
      │
      ▼
┌──────────────────────────────────┐
│ Index 비트로 집합(Set) 선택      │
└──────────────┬───────────────────┘
               ▼
┌──────────────────────────────────┐
│ N-Way 병렬 태그(Tag) 비교        │
└──────┬───────────────┬───────────┘
 [Hit] │               │ [Miss]
       ▼               ▼
┌────────────┐ ┌───────────────────┐
│ Offset Data│ │ LRU 희생 라인     │
│ Data 반환  │ │ 축출 및 Refill    │
└────────────┘ └───────────────────┘
```

### 동작 원리

1. 집합 인덱싱: 주소의 **인덱스** 비트를 디코딩하여 특정 캐시 집합(Set)을 선택함.
2. 태그 비교: 선택된 집합 내 모든 Way의 **유효 비트**와 **태그**를 병렬로 비교함.
3. 적중 처리: 일치하는 태그가 있으면(**캐시 적중**) 데이터 배열에서 **오프셋** 위치의 데이터를 즉시 반환함.
4. 미스 처리: 일치하는 태그가 없으면(**캐시 미스**) **LRU** 정책으로 기존 라인을 축출하고 새 블록을 리필함.

#### 한줄 요약

- 주소의 인덱스로 집합을 선택한 뒤, 태그 병렬 비교 결과에 따라 데이터를 즉시 반환하거나 캐시 라인을 교체한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 매핑(Direct Mapping)**: 1개 블록이 오직 1개 정해진 캐시 라인 위치로만 매핑되는 단순 방식 (Set 1개당 Way 1개).
- **완전 연관 매핑(Fully Associative Mapping)**: Index 필드 없이 메인 메모리 블록이 캐시의 임의의 아무 라인에나 들어갈 수 있는 구조.
- **집합 연관 매핑(Set-Associative Mapping)**: 전체 캐시를 여러 Set으로 나누고 각 Set 내에 N개의 Way(2, 4, 8, 16-Way)를 두는 범용 절충 방식.

</details>

| 매핑 방식 | 직접 매핑 | 완전 연관 매핑 | 집합 연관 매핑 |
|:---|:---|:---|:---|
| 적용 기준 | 캐시 라인별 고정 위치 배치 | 전체 라인 내 자율 배치 | 특정 집합 내 **N-Way** 자율 배치 |
| 핵심 특징 | 1개 태그만 단일 비교 | 전체 태그 동시 병렬 비교 | N개 Way 태그만 병렬 비교 |
| 한계 | 잦은 **충돌 미스** 발생 | 탐색 지연 및 구현 비용 최대 | 연관도에 따른 **적중 시간** 절충 |
| 주소 구조 | Tag + Index + Offset | Tag + Offset | Tag + Index + Offset |
| 실무 채택 | 고속 L1 명령 캐시, 저가 MCU | **TLB** | 현대 프로세서의 캐시 표준 규격 |

#### 한줄 요약

- 속도가 빠른 직접 매핑과 충돌이 없는 완전 연관 매핑의 한계를 절충하여 집합 연관 매핑을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비차단 캐시(Non-Blocking Cache)**: 미스 처리 중에도 멈추지 않고 다른 캐시 요청을 계속 가동하는 기술이다.
- **프리페치(Prefetching)**: 공간 및 시간 지역성을 분석하여 접근할 데이터를 미스 발생 전에 캐시로 인출하는 기술이다.
- **Pseudo-LRU (PLRU)**: N-Way 연관도가 높을 때 면적과 트래픽 비용을 줄이기 위해 트리를 기반으로 LRU를 흉내 내는 정책이다.
- **주소 배치(Cache Alignment)**: 자료구조 배치 시 캐시 라인 경계에 맞추어 충돌 미스 및 캐시 라인 걸침을 예방하는 코드 최적화이다.
- **Way 예측기(Way Predictor)**: 태그를 모두 비교하기 전에 접근할 확률이 높은 Way를 미리 추측하여 전력을 아끼는 장치이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특정 집합 쏠림에 따른 **충돌 미스** | **집합 연관 매핑** 확장•**주소 배치** 최적화 | 메모리 블록 쏠림 완화 |
| 연관도 증가로 태그 탐색 전력 폭증 | **Pseudo-LRU**•**Way 예측기** 도입 | 탐색 지연 및 전력 감소 |
| 미스 발생 시 파이프라인 정지 | **비차단 캐시**•하드웨어 **프리페치** | 메모리 접근 지연 은닉 |

#### 한줄 요약

- 다중 Way, 메모리 정렬, 교체 최적화 및 프리페치를 결합하여 충돌 미스와 탐색 지연을 동시에 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **연관도 확대**: 충돌 미스를 줄이기 위해 캐시 집합 내의 Way 수를 늘리는 구조적 변경이다.
- **저연관도**: 적중 시간을 최소화하기 위해 Way 수를 적게 유지하는 캐시 설계 방식이다.

</details>

- 적중 지연이 우선이면 **저연관도**, 충돌 미스가 크면 **연관도 확대**로 대응함.

#### 한줄 요약

- 측정한 **AMAT** 지표를 바탕으로 계층별 요구사항에 맞는 연관도와 교체 정책을 결정함.
