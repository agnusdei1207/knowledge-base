## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 메모리(Cache Memory)**: CPU 코어와 메인 메모리(DRAM) 사이에 위치하여 참조 지역성을 기반으로 빈번히 접근하는 데이터를 임시 보관하는 초고속 온칩 SRAM 기억장치.
- **캐시 매핑(Cache Mapping)**: 메인 메모리의 특정 데이터 블록 주소를 캐시 메모리의 캐시 라인(슬롯) 위치로 대응시키는 하드웨어 주소 사상 기법.
- **캐시 라인(Cache Line)**: 캐시와 주기억장치 간 데이터 전송 기본 단위(일반적으로 64바이트)로, 태그(Tag), 상태 비트(Valid/Dirty), 데이터 블록으로 구성.
- **태그(Tag)**: 메모리 주소의 최상위 비트 필드로, 캐시 라인에 적재된 블록이 CPU가 요청한 메모리 주소와 일치하는지 판별하는 식별자.

</details>

- 정의/개념: 주기억장치의 데이터 블록을 캐시 메모리 내 어떤 슬롯에 적재할지를 결정하는 **주소 비트 분할(태그·인덱스·오프셋) 기반 캐시 매핑 아키텍처**
- 배경/필요성: 고속 태그 비교 회로 비용과 **동일 집합 충돌 미스(Conflict Miss) 발생에 따른 평균 메모리 접근 시간(AMAT) 증가 간의 상충** 해결

#### 한줄 요약
- 캐시 매핑은 주기억장치 블록을 캐시 라인에 배치하는 규칙이며, 직접 매핑, 완전 연관 매핑, 집합 연관 매핑으로 구분된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공간 지역성(Spatial Locality)**: 특정 메모리 주소 참조 시 그 인접한 주소들이 곧바로 참조될 가능성이 높은 프로그램 특성(64B 라인 단위 반입의 근거).
- **시간 지역성(Temporal Locality)**: 최근 참조된 데이터가 가까운 미래에 다시 참조될 가능성이 높은 특성(캐시 라인 유지의 근거).
- **충돌 미스(Conflict Miss)**: 캐시 용량이 충분히 남아있음에도 동일한 집합(Set) 또는 라인으로 다수 블록이 사상되어 발생하는 캐시 미스.
- **연관도(Set Associativity)**: 단일 집합(Set) 내에 포함된 캐시 라인의 개수(N-way)로, 연관도가 높을수록 충돌 미스는 감소하나 태그 비교 지연과 전력이 증가.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: $AMAT = T_{hit} + (Miss\,Rate \times Miss\,Penalty)$로 산출되는 메모리 서브시스템의 총체적 성능 척도.

</details>

- 지역성 극대화: 라인 단위 일괄 반입으로 **공간 지역성**을, 캐시 라인 보존으로 **시간 지역성**을 활용하여 적중률 향상
- 연관도와 하드웨어 비용 상충: **연관도(Associativity)**를 높일수록 **충돌 미스**는 줄어드나 병렬 태그 비교 회로(비교기, MUX)로 인해 적중 시간($T_{hit}$)과 전력 소모 증가
- AMAT 최적화: 적중 시간($T_{hit}$), 미스율(Miss Rate), 미스 페널티(Miss Penalty)의 곱과 합으로 산출되는 **AMAT**를 최소화하도록 매핑 방식 선정

#### 한줄 요약
- 연관도를 높이면 충돌 미스는 줄지만 적중 시간이 늘어나므로, AMAT가 최소가 되는 최적의 집합 연관도를 설계해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 오프셋(Block Offset)**: 캐시 라인(64B) 내부에서 CPU가 요청한 특정 바이트/워드의 위치를 지정하는 주소 최하위 비트 필드.
- **집합 인덱스(Set Index)**: 메모리 주소의 중간 비트 필드로, 집합 연관 캐시에서 해당 블록이 사상될 캐시 집합(Set) 번호를 선택하는 인덱스.
- **유효 비트(Valid Bit)**: 해당 캐시 라인에 유효한 데이터가 적재되어 있는지 여부를 나타내는 1비트 상태 플래그.
- **교체 정책(Replacement Policy)**: 집합 내 모든 Way가 가득 찬 상태에서 새 블록을 적재할 때 희생 라인을 선정하는 하드웨어 알고리즘(LRU, Pseudo-LRU, FIFO 등).

</details>

```text
[CPU 가상/물리 주소 구조 (예: 64-bit)]
 ┌────────────────────────────────┬────────────────────────┬──────────────────────┐
 │          태그 (Tag)            │    집합 인덱스 (Index)  │  블록 오프셋 (Offset) │
 └────────────────────────────────┴────────────────────────┴──────────────────────┘
                 │                                │                         │
                 ▼                                ▼                         ▼
    [태그 비교기 (Tag Comparator)]        [집합 디코더 (Decoder)]    [바이트 선택 MUX]
                 │                                │                         │
 ┌───────────────┴────────────────────────────────┴─────────────────────────┴──────┐
 │ [N-Way 집합 연관 캐시 메모리 어레이]                                            │
 │  Set 0: [Way 0 (V|Tag|Data)] [Way 1 (V|Tag|Data)] ··· [Way N-1 (V|Tag|Data)]    │
 │  Set 1: [Way 0 (V|Tag|Data)] [Way 1 (V|Tag|Data)] ··· [Way N-1 (V|Tag|Data)]    │
 │   ···                                                                           │
 └─────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 주소 비트 필드가 캐시 하드웨어의 집합 선택, N개 Way 병렬 태그 비교, 데이터 오프셋 추출로 각각 전달되는 계층적 제어 흐름

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **태그 (Tag)** | 주소 최상위 필드 | 캐시 라인에 적재된 블록과 CPU 요청 블록의 일치 판별 | N개 Way 병렬 비교기 구동 |
| **집합 인덱스 (Index)** | 주소 중간 필드 | 접근할 캐시 집합(Set) 번호 1개 선택 | $2^{Index} = 집합\,수$ |
| **블록 오프셋 (Offset)**| 주소 최하위 필드 | 64바이트 캐시 라인 내 요청 바이트/워드 추출 | 64B 기준 6비트($2^6=64$) |
| **유효 비트 (Valid Bit)**| 캐시 라인 헤더 | 데이터 유효성 표시 (부팅/플러시 시 0 클리어) | 태그 일치 시 함께 판정 |
| **교체 제어기** | 캐시 컨트롤러 | N개 Way가 모두 찼을 때 **교체 정책(LRU)**에 따라 희생 라인 선정 | N-Way 연관 캐시 전용 로직 |

#### 한줄 요약
- 캐시 메모리는 주소를 태그, 인덱스, 오프셋으로 분할하여 집합을 고르고 N개 Way의 태그를 병렬 비교하여 데이터를 인출한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 적중(Cache Hit)**: CPU 요청 주소의 블록이 캐시 내 유효한 상태로 존재하여 즉시 데이터를 반환하는 상태.
- **캐시 미스(Cache Miss)**: 요청 데이터가 캐시에 없어 하위 메모리 계층(L2/L3/DRAM)에서 블록을 인출해야 하는 상태.
- **희생 라인(Victim Line)**: 미스 발생 시 새로운 블록을 적재하기 위해 캐시에서 축출(Eviction)되는 기존 캐시 라인.

</details>

```text
1. CPU 코어가 메모리 읽기/쓰기 주소 발행
                      │
                      ▼
2. 인덱스(Index) 비트로 캐시 집합(Set) 선택
                      │
                      ▼
3. 집합 내 N개 Way의 유효 비트 및 태그를 병렬 비교
   ┌──────────────────┴──────────────────┐
[ 일치 (Cache Hit) ]                  [ 불일치/무효 (Cache Miss) ]
   │                                     │
   ▼                                     ▼
오프셋(Offset)으로 데이터 선택        4. 하위 메모리(L2/L3/DRAM)에서 64B 블록 인출
   │                                     │
   ▼                                     ▼
1~4 사이클 내 코어 반환 완료          5. 집합 내 빈 라인 존재 여부 확인
                                         ├─ 빈 라인 있음 ➔ 즉시 적재
                                         └─ 꽉 참 ➔ LRU 교체 정책으로 희생 라인 축출 후 적재
                                         │
                                         ▼
                                      6. 태그/유효 비트 갱신 및 데이터 코어 전달
```

분기 결과: **적중 시에는** 1~4클록 내에 즉시 반환되나, **미스 시에는** 하위 메모리 접근 및 희생 라인 교체로 인해 수십~수백 클록의 미스 패널티가 발생함

#### 한줄 요약
- 캐시 접근은 인덱스로 집합을 고르고 N개 Way의 태그를 병렬 비교하여 적중 시 즉시 반환하고, 미스 시 하위 메모리에서 블록을 반입한다.

## Ⅴ. 종류 및 비교

| 매핑 방식 | 직접 매핑 (Direct Mapped) | 집합 연관 매핑 (Set Associative) | 완전 연관 매핑 (Fully Associative) |
|:---|:---|:---|:---|
| 집합당 Way 수 | **1-Way (집합당 라인 1개)** | **N-Way (일반적으로 2, 4, 8, 16-Way)** | **All-Way (전체 캐시가 단일 집합)** |
| 장점 | 태그 비교기 1개로 회로 단순, 최단 적중 시간 | **충돌 미스 감소와 적중 시간의 최적 절충** | **충돌 미스 0% (배치 유연성 극대화)** |
| 한계 | **동일 인덱스 블록 간 충돌 미스 빈발** | 연관도 증가 시 비교 회로 복잡도 및 전력 증가 | 대용량 적용 불가 (비교기 수 = 전체 라인 수) |
| 주요 적용처 | 단순 임베디드 코어, 초고속 L1 캐시 일부 | **현대 CPU의 L1, L2, L3 캐시 표준** | **소용량 TLB (64~128 엔트리)** |

#### 한줄 요약
- 속도 우선은 직접 매핑, 배치 유연성 우선은 완전 연관 매핑이며, 현대 프로세서는 둘의 장점을 절충한 집합 연관 매핑을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인덱스 해싱(Index Hashing)**: 주소 비트들을 XOR 연산 등으로 섞어 인덱스를 고르게 분산시킴으로써 특정 캐시 집합으로의 핫스팟 충돌을 방지하는 기법.
- **비차단 캐시(Non-blocking Cache)**: 캐시 미스가 발생하여 하위 메모리에서 데이터를 가져오는 중에도 후속 적중/미스 요청을 병렬 처리하는 캐시.
- **MSHR(Miss Status Holding Register)**: 비차단 캐시에서 진행 중인 미스 트랜잭션을 추적하고 후속 요청을 매핑하는 하드웨어 테이블.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 2의 거듭제곱 스트라이드 접근으로 특정 집합에 **충돌 미스** 집중 | **인덱스 해싱(XOR Hashing)** 및 연관도 확장 | 집합 편중 현상 제거 및 충돌 미스 대폭 감소 |
| 연관도 증가로 인한 태그 비교 회로의 동적 전력 급증 | **Way 예측(Way Prediction)** 기술 적용 | 1개 Way만 우선 활성화하여 직접 매핑 수준 저전력 달성 |
| 캐시 미스 발생 시 파이프라인 전체가 스톨되는 문제 | **비차단 캐시(Non-blocking Cache) 및 MSHR** 탑재 | 미스 중에도 독립된 캐시 요청을 병렬 처리하여 지연 은닉 |

#### 한줄 요약
- 실무 캐시 설계는 인덱스 해싱으로 충돌 미스를 분산하고, Way 예측으로 전력을 절감하며, 비차단 캐시(MSHR)로 미스 지연을 은닉한다.

## Ⅶ. 결론

- 메모리 계층의 성능(AMAT)을 최적화하기 위해 **L1/L2/L3 온칩 캐시에는 충돌 미스와 적중 시간의 균형이 입증된 4~16 Way 집합 연관 매핑을 표준 채택**하고, 소용량 고속 변환 구조인 **TLB에는 완전 연관 매핑을 적용**하며, **인덱스 해싱과 MSHR 기반 비차단 캐시 기술을 융합**하여 프로세서-메모리 간 성능 격차(Memory Wall)를 극복하는 고성능 캐시 서브시스템 구축

#### 한줄 요약
- 캐시 매핑은 AMAT를 최소화하는 연관도 설계가 핵심이며, 현대 시스템은 집합 연관 매핑을 기반으로 비차단 캐시 기술을 결합하여 고성능을 완성한다.
