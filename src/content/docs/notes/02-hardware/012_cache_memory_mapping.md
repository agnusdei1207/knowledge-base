## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 메모리(Cache Memory)**: CPU와 주기억장치 사이에 위치하여 빈번히 사용되는 데이터와 명령어를 임시 저장함으로써 메모리 접근 지연시간을 단축하는 고속 SRAM 메모리.
- **캐시 매핑(Cache Mapping)**: 주기억장치의 데이터 블록 주소를 캐시 메모리의 특정 캐시 라인(슬롯) 위치로 대응시키는 하드웨어 주소 사상 기법.
- **캐시 라인(Cache Line)**: 캐시와 주기억장치 간의 데이터 전송 기본 단위(보통 64바이트)로, 태그(Tag), 상태 비트(Valid/Dirty), 데이터 블록으로 구성.
- **태그(Tag)**: 메모리 주소의 최상위 비트 필드로, 캐시 라인에 적재된 블록이 CPU가 현재 요청한 블록과 일치하는지 판별하는 식별자.

</details>

- 정의/개념: 주기억장치 블록이 **캐시 라인** 중 어디에 앉을 수 있는지를 **태그**와 인덱스 비트로 정하는 **캐시 매핑** 규칙
- 배경/필요성: 동일 인덱스에 참조가 집중되면 **충돌 미스**가 반복되어 평균 메모리 접근 시간 증가

#### 한줄 요약
- 매핑은 자리를 넓힐수록 자리다툼이 줄지만 그만큼 찾는 데 시간이 걸리므로, 미스를 줄이는 이득과 적중을 늦추는 손해가 정면으로 부딪친다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공간 지역성(Spatial Locality)**: 특정 메모리 주소가 참조되었을 때 그 인접한 주소들이 가까운 미래에 연속으로 참조될 가능성이 높은 프로그램 특성(캐시 블록 단위 전송의 근거).
- **시간 지역성(Temporal Locality)**: 최근 참조된 메모리 주소가 가까운 미래에 반복해서 다시 참조될 가능성이 높은 프로그램 특성(캐시 적중률 유지의 근거).
- **충돌 미스(Conflict Miss)**: 캐시 용량이 충분히 남아있음에도 불구하고 여러 메모리 블록이 동일한 캐시 집합(Set) 또는 라인으로 사상되어 발생하는 캐시 미스.
- **연관도(Set Associativity)**: 집합 연관 캐시에서 단일 집합(Set)이 수용할 수 있는 캐시 라인의 개수(N-way)로, 연관도가 높을수록 충돌 미스는 줄어드나 태그 비교 회로 지연과 전력이 증가.
- **적중 시간(Hit Time)**: 캐시 메모리에서 주소 디코딩, 태그 비교 및 데이터 인출을 완료하여 CPU에 반환하는 데 걸리는 클록 사이클 시간.
- **미스 패널티(Miss Penalty)**: 캐시 미스 발생 시 하위 메모리 계층에서 해당 블록을 인출하여 캐시를 리필하고 CPU에 전달하는 데 소요되는 추가 지연시간.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: CPU가 메모리에 접근할 때 소요되는 평균 지연시간으로, $AMAT = T_{hit} + (Miss\,Rate \times Miss\,Penalty)$로 산출.

</details>

- 라인 단위 반입으로 **공간 지역성**을, 라인 보존으로 **시간 지역성**을 각각 활용
- 후보 라인 수(연관도)가 클수록 **충돌 미스** 감소·비교 회로 비용 증가의 상충
- 적중 시간·미스율·미스 패널티를 결합한 **AMAT**로 매핑 효율 판단

#### 한줄 요약
- **AMAT** 식이 세 항의 곱과 합으로 되어 있다는 사실 자체가 답이며, 미스율만 낮춰도 적중 시간이 늘면 총합은 오히려 나빠질 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 오프셋(Block Offset)**: 캐시 라인 내부에서 CPU가 요청한 특정 바이트나 워드의 위치를 지정하는 주소 최하위 비트 필드.
- **집합 인덱스(Set Index)**: 메모리 주소의 중간 비트 필드로, 집합 연관 캐시에서 해당 블록이 매핑될 캐시 집합(Set) 번호를 선택하는 인덱스.
- **유효 비트(Valid Bit)**: 해당 캐시 라인에 유효한 데이터가 적재되어 있는지 여부를 나타내는 1비트 상태 플래그.
- **교체 정책(Replacement Policy)**: 캐시 집합이 가득 찬 상태에서 미스 발생 시 새로운 블록을 적재하기 위해 희생 라인(Victim Line)을 선정하는 알고리즘(LRU, LFU, FIFO, Random 등).

</details>

```text
[주소]
├─ 태그           ← 라인 일치 판별
├─ 집합 인덱스    ← 후보 집합 선택
└─ 블록 오프셋    ← 라인 내 위치 선택

[캐시 라인]
├─ 유효 비트
├─ 태그
├─ 데이터 블록
└─ 교체 상태
```

선의 의미: 가지는 포함 관계; 주소 필드와 라인 구성요소의 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| **태그** | 적재 블록과 요청 블록이 같은지 판별 |
| 집합 인덱스 | 후보 라인 집합 선택 |
| 블록 오프셋 | 라인 내 요청 바이트 위치 선택 |
| 유효 비트 | 라인 데이터의 사용 가능 여부 표시 |
| 데이터 블록 | 주기억장치에서 반입한 라인 단위 데이터 보관 |
| 교체 상태 | **교체 정책**이 방출 대상을 고르는 근거 보관 |

#### 한줄 요약
- 주소 비트를 어디서 끊느냐가 곧 캐시 구조이므로, 같은 용량이라도 인덱스 폭을 한 비트 옮기면 완전히 다른 충돌 패턴을 갖는 캐시가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 적중(Cache Hit)**: CPU가 요청한 메모리 주소의 데이터가 캐시 메모리에 유효한 상태(Valid)로 존재하여 태그 비교가 일치하고 즉시 데이터를 반환하는 상태.
- **캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없거나 유효하지 않아 하위 메모리 계층으로부터 블록을 인출해야 하는 상태.
- **희생 라인(Victim Line)**: 캐시 미스 발생 시 새로운 데이터 블록을 적재하기 위해 교체 정책에 의해 캐시에서 축출(Eviction)되는 기존 캐시 라인.

</details>

```text
주소 입력
   │
   ▼
[ 1. 인덱스 기반 집합 선택 ]
   │
   ▼
[ 2. 태그 일치 판별 및 적중 처리 ]
   │
   ├─ 일치 → 블록 오프셋으로 데이터 즉시 반환
   │
   └─ 불일치/무효 → [ 3. 미스 반입 및 희생 라인 교체 ]
                           │
                           ▼
                     주기억장치 반입 및 태그·유효 비트 갱신
```

분기 결과: **캐시 적중**은 태그 비교 한 번으로 끝나지만 **캐시 미스**는 **희생 라인** 선정·축출·반입이 연쇄되어, 두 경로의 비용 차이가 수십 배로 벌어짐

#### 한줄 요약
- 미스 경로가 압도적으로 비싸기 때문에 캐시 설계의 모든 선택은 적중 경로를 짧게 두면서 미스 빈도를 낮추는 한 방향으로 수렴한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 매핑(Direct Mapping)**: 주기억장치의 각 블록이 지정된 단 하나의 캐시 라인에만 사상되는 1-Way 매핑 방식으로, 구조가 단순하고 적중 시간이 빠르나 충돌 미스 발생률이 높음.
- **완전 연관 매핑(Fully Associative Mapping)**: 주기억장치 블록이 캐시 내의 어떤 라인에도 자유롭게 배치될 수 있는 매핑 방식으로, 충돌 미스를 완전히 제거하나 모든 라인의 태그를 병렬 비교하는 고비용 하드웨어가 필요.
- **집합 연관 매핑(Set Associative Mapping)**: 캐시를 여러 집합(Set)으로 나누고 각 집합 내에 N개의 라인을 두어 블록이 특정 집합 내 임의의 라인에 사상되도록 하는 절충형 매핑 방식(N-Way).

</details>

| 매핑 방식 | 직접 매핑 | 집합 연관 매핑 | 완전 연관 매핑 |
|:---|:---|:---|:---|
| 적용 기준 | 단순 구조·최단 적중 경로가 우선이고 충돌 미스 허용 가능 | 충돌 미스 완화와 구현 비용 균형이 필요 | 소용량 구조에서 충돌 미스 배제 요구 |
| 핵심 특징 | 후보 라인이 1개뿐이라 태그 비교가 최소 | 집합 내 **연관도** 조정으로 충돌 완화 | 모든 라인이 후보라 배치 유연성 최대 |
| 한계 | 동일 인덱스 블록 간 **충돌 미스** 불가피 | Way 수 증가에 따른 태그 비교 회로·전력 증가 | 전역 태그 병렬 탐색 비용으로 대용량 적용 제약 |

#### 한줄 요약
- 세 방식은 별개의 기법이 아니라 연관도를 1에서 전체 라인 수까지 움직인 같은 축의 양 끝과 중간이며, 실제 설계는 언제나 그 중간 어딘가를 고른다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인덱스 해싱(Index Hashing)**: 주소 비트열의 XOR 연산 등을 통해 인덱스를 재분산시킴으로써 특정 집합으로 요청이 편중되는 핫스팟 현상과 충돌 미스를 완화하는 기법.
- **비차단 캐시(Non-blocking Cache)**: 캐시 미스가 발생하여 하위 메모리에서 블록을 가져오는 중에도 후속 캐시 적중/미스 요청을 중단 없이 병렬 처리할 수 있는 캐시 구조.
- **미스 상태 유지 레지스터(Miss Status Holding Register, MSHR)**: 비차단 캐시에서 처리 중인 미스 요청의 주소, 데이터 목적지 및 대기 중인 후속 요청 목록을 추적 관리하는 하드웨어 레지스터.
- **프리페치(Prefetch)**: 데이터 접근 패턴(순차, 스트라이드 등)을 분석하여 CPU가 실제 요청하기 전에 필요한 블록을 하위 메모리에서 캐시로 미리 인출해두는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 핫 블록이 같은 집합에 집중해 **충돌 미스** 반복 | 연관도 증가 또는 인덱스 해싱으로 집합 분산 | 충돌 미스율 감소·반복 반입 감소 |
| 연관도 증가로 태그 비교 회로 전력 급등 | Way 예측 후 선택적 Way만 활성화 | $T_{hit}$ 유지하며 전력 절감 |
| 미스 처리 중 독립 요청이 대기 상태로 정지 | **MSHR** 기반 비차단 캐시 도입 | 메모리 수준 병렬성 향상 |
| 과도한 **프리페치**로 유용한 라인 조기 방출 | 적중률·오염도·대역폭 기준 프리페치 정책 조정 | 불필요한 반입 감소·유효 라인 보호 |

#### 한줄 요약
- **인덱스 해싱**과 **비차단 캐시**는 미스를 줄이는 대신 미스 비용을 감추는 대책이며, 미스율이 이미 낮은 워크로드에서는 후자 쪽이 훨씬 큰 이득을 낸다.

## Ⅶ. 결론

- 워크로드의 **AMAT**를 **적중 시간**과 **미스 패널티**로 분해해 직접·집합 연관 매핑을 선택하고, 완전 연관 매핑은 탐색 비용을 감당할 수 있는 소용량 구조로 한정

#### 한줄 요약
- 매핑 선택이 어려운 이유는 두 비용이 서로 반대 방향으로 움직여서이며, 하나만 보고 고르면 반드시 다른 하나에서 잃는다.
