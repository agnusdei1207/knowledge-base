## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시(Cache)**: 자주 접근하는 하위 계층 데이터를 프로세서 가까이에 복사해 접근 지연을 줄이는 메모리입니다.
- **캐시 매핑(Cache Mapping)**: 메모리 블록이 캐시에서 들어갈 수 있는 후보 위치를 정하는 주소 사상 규칙입니다.
- **캐시 라인(Cache Line)**: 캐시와 하위 메모리 사이에서 함께 이동하는 데이터 블록 단위입니다.
- **태그(Tag)**: 선택한 캐시 위치의 데이터가 요청한 메모리 블록과 같은지 판정하는 주소 상위 정보입니다.

</details>

- 정의/개념: 블록의 후보 라인과 태그 판정을 정하는 **캐시 주소 사상 기법**
- 배경/필요성: 메모리 벽과 동일 위치 경쟁의 충돌 미스 완화

#### 한줄 요약

- 캐시 매핑은 책 한 권이 서가의 어디에 놓일 수 있는지 정하는 규칙이며, 위치가 좁으면 찾기 쉽지만 서로 자리를 빼앗기기 쉽습니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공간 지역성(Spatial Locality)**: 한 주소를 사용하면 가까운 주소도 곧 사용할 가능성이 높은 성질입니다.
- **시간 지역성(Temporal Locality)**: 최근 사용한 데이터가 다시 사용될 가능성이 높은 성질입니다.
- **충돌 미스(Conflict Miss)**: 캐시 용량이 충분해도 같은 후보 위치를 공유한 블록들이 서로 교체하며 발생하는 미스입니다.
- **연관도(Associativity)**: 하나의 집합에서 블록이 들어갈 수 있는 라인 수입니다.

</details>

- 라인 단위 반입으로 활용하는 **공간 지역성**
- 최근 라인 재사용으로 활용하는 **시간 지역성**
- 후보 라인 수에 따라 달라지는 **충돌 미스**

$$
AMAT = T_{hit} + Miss\ Rate \times Miss\ Penalty
$$

- 평균 접근 시간: 적중 시간·미스율·미스 비용의 **AMAT 판단식**

#### 한줄 요약

- 캐시는 근처 데이터와 최근 데이터를 함께 가져오는 습관을 이용하고, 매핑 방식은 서로 다른 블록이 같은 자리를 차지하려는 충돌을 얼마나 줄일지 결정합니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 오프셋(Block Offset)**: 캐시 라인 안에서 요청한 바이트 또는 워드 위치를 고르는 주소 비트입니다.
- **집합 인덱스(Set Index)**: 집합 연관 캐시에서 후보 라인 묶음을 고르는 주소 비트입니다.
- **유효 비트(Valid Bit)**: 캐시 라인에 사용 가능한 데이터가 들어 있는지 나타내는 상태 비트입니다.
- **교체 정책(Replacement Policy)**: 집합이 가득 찼을 때 새 라인을 위해 내보낼 라인을 고르는 규칙입니다.

</details>

```text
[캐시 라인]
├─ 태그
├─ 유효 비트
├─ 데이터 블록
└─ 교체 상태

[주소]
├─ 태그
├─ 집합 인덱스
└─ 블록 오프셋
```

| 구성요소 | 책임 |
|:---|:---|
| 태그 | 요청 블록과 저장 블록의 일치 판정 |
| 유효 비트 | 라인 데이터의 사용 가능 여부 표시 |
| 데이터 블록 | 라인 단위 데이터 보관 |
| 집합 인덱스 | 후보 라인 묶음 선택 |
| 블록 오프셋 | 라인 내부 요청 위치 선택 |
| 교체 상태 | 미스 때 희생 라인 선택 |

#### 한줄 요약

- 주소는 어느 서가를 볼지와 그 안의 어느 책인지로 나뉘고, 태그는 찾은 책이 정말 원하는 책인지 확인합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 적중(Cache Hit)**: 요청한 데이터가 캐시에 있어 하위 메모리 접근 없이 반환되는 상황입니다.
- **캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없어 하위 계층에서 라인을 가져와야 하는 상황입니다.
- **희생 라인(Victim Line)**: 새 라인을 넣기 위해 교체 대상으로 선택한 기존 캐시 라인입니다.

</details>

```text
[1. 주소 분해]
          │
          ▼
[2. 집합 선택·태그 비교]
          │
          ▼
[3. 적중 데이터 반환]
          │
          └─ 미스
               │
               ▼
          [4. 희생 라인 교체·라인 반입]
```

동작 원리:

1. 주소 분해: 태그·집합 인덱스·블록 오프셋 분리
2. 집합 선택·태그 비교: 후보 라인의 유효 비트와 태그 확인
3. 적중 데이터 반환: 일치 라인의 오프셋 위치 데이터 제공
4. 희생 라인 교체·라인 반입: 하위 계층 요청 뒤 상태와 태그 갱신

#### 한줄 요약

- 캐시는 먼저 후보 서가를 좁히고 이름표를 비교해 바로 주거나, 없으면 오래된 책을 빼고 새 책 한 줄을 가져옵니다.

## Ⅴ. 종류 및 비교

| 매핑 방식 | 직접 매핑 | 완전 연관 매핑 | 집합 연관 매핑 |
|:---|:---|:---|:---|
| 적용 기준 | 짧은 적중 경로와 단순 구조 우선 | 작은 구조의 최대 배치 유연성 필요 | 충돌 완화와 비용 균형 필요 |
| 핵심 특징 | 블록당 후보 라인 1개 | 모든 라인이 후보 | 선택 집합의 여러 라인이 후보 |
| 한계 | 같은 인덱스 블록의 충돌 미스 | 전역 태그 탐색·교체 비용 | way 비교·교체 상태 비용 |

#### 한줄 요약

- 직접 매핑은 지정석 하나만 보는 방식, 완전 연관은 빈자리를 모두 찾는 방식, 집합 연관은 정해진 구역 안에서 몇 자리를 고르는 방식입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인덱스 해싱(Index Hashing)**: 주소 비트를 조합해 특정 집합으로 요청이 쏠리는 현상을 줄이는 방식입니다.
- **비차단 캐시(Non-blocking Cache)**: 한 미스가 진행 중이어도 독립 적중·미스를 계속 처리할 수 있는 캐시입니다.
- **미스 상태 보관 레지스터(Miss Status Holding Register, MSHR)**: 진행 중인 미스 요청과 대기 요청을 추적하는 구조입니다.
- **프리페치(Prefetch)**: 앞으로 사용할 가능성이 있는 데이터를 미리 캐시로 가져오는 기법입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 핫 블록이 같은 집합에서 반복 교체 | 연관도·인덱스 해싱·데이터 배치 조정 | 충돌 미스와 반복 반입 감소 |
| 연관도 증가로 태그 비교 전력 증가 | way 예측과 선택적 way 활성화 적용 | 적중 지연·전력·미스율 균형 |
| 한 미스가 독립 요청까지 정지 | MSHR 기반 비차단 캐시 적용 | 메모리 수준 병렬성 향상 |
| 과도한 프리페치가 유용한 라인 축출 | 적중률·오염·대역폭 기준 정책 조정 | 프리페치 부작용 감소 |

#### 한줄 요약

- 캐시 설계는 연관도 하나만 높이는 문제가 아니라, 주소가 어디에 몰리는지와 미스 중에도 다른 일을 할 수 있는지까지 함께 다뤄야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **적중 시간(Hit Time)**: 캐시에 데이터가 있을 때 요청부터 데이터 반환까지 걸리는 시간입니다.
- **미스 패널티(Miss Penalty)**: 캐시 미스 뒤 하위 계층에서 데이터를 가져오며 추가로 드는 시간입니다.

</details>

- 워크로드의 충돌 미스가 우세하면 **집합 연관 매핑**을 확대하고, 지연·전력 제약이 우선이면 직접 매핑을 검토하되 **적중 시간**·미스 패널티·면적을 AMAT로 함께 평가

#### 한줄 요약

- 좋은 캐시 매핑은 가장 복잡한 방식을 고르는 일이 아니라, 실제 주소 충돌로 잃는 시간과 더 복잡한 비교 회로에 드는 시간을 함께 재서 고르는 일입니다.
