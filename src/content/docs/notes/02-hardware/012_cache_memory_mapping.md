## 미리 알고가기

- **캐시 매핑(Cache Mapping)**: 짐 하나가 사물함 어느 칸에 들어갈 수 있고 찾을 때 이름표를 몇 개나 확인해야 하는지를 미리 정해 둔 규칙이며, 후보 칸을 한 칸으로 못 박을지 전체로 열어 둘지 몇 칸 묶음으로 절충할지가 이 문서의 갈림길이다
- **캐시 라인(Cache Line)**: 캐시와 메모리가 한 번에 주고받는 고정 크기 덩어리이며 사물함 한 칸에 들어가는 짐 한 뭉치에 해당한다
- **연관도(Associativity)**: 메모리 블록 하나가 들어갈 수 있는 후보 라인이 몇 개인지이며, 1이면 직접 매핑이고 전체 라인 수와 같으면 완전 연관이다
- **집합과 웨이(Set and Way)**: 집합은 같은 인덱스를 갖는 후보 라인 묶음이고 웨이는 그 묶음 안의 개별 라인이며, 4-웨이라면 한 집합에 후보가 넷이라는 뜻이다
- **태그·인덱스·오프셋(Tag·Index·Offset)**: 메모리 주소를 셋으로 갈라 인덱스로 어느 집합인지 고르고 태그로 그 집합 안의 어느 블록인지 가려내며 오프셋으로 라인 안 몇 번째 바이트인지 찾는다
- **주소 필드(Address Field)**: 주소를 위 세 역할에 몇 비트씩 떼어 준 구간이며 캐시 용량·라인 크기·연관도가 정해지면 이 폭도 함께 정해진다
- **유효 비트(Valid Bit)**: 그 라인에 실제 의미 있는 데이터가 들어 있는지를 표시하는 한 비트이며, 태그가 우연히 맞아도 이 비트가 꺼져 있으면 미스다
- **캐시 적중(Cache Hit)·캐시 미스(Cache Miss)**: 찾는 데이터가 캐시에 있어 바로 돌려주면 적중, 없어서 아래 계층까지 다녀와야 하면 미스다
- **충돌 미스(Conflict Miss)**: 캐시에 빈자리가 있는데도 그 블록이 갈 수 있는 후보 칸이 이미 다른 블록에 차 있어 어쩔 수 없이 나는 미스
- **적중 시간·미스율·미스 페널티(Hit Time·Miss Rate·Miss Penalty)**: 캐시를 뒤지는 데 걸리는 시간, 전체 접근 중 미스가 난 비율, 미스 한 번에 아래 계층까지 다녀오는 추가 지연이며 이 셋이 평균 접근 시간을 만든다
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: ‘에이맷’으로 읽고 영문 머리글자를 단어처럼 읽는 약어이며, 적중 시간·미스율·미스 페널티를 합친 평균 접근 지연이다
- **지역성(Locality)**: 프로그램이 방금 쓴 주소나 그 근처를 다시 찾는 성질이며, 이것이 강할수록 후보 칸을 늘려 얻는 미스 감소 효과도 커진다
- **직접 매핑(Direct Mapping)**: 블록이 갈 수 있는 칸을 인덱스로 계산한 한 칸으로 못 박아 이름표를 하나만 확인하면 되는 방식
- **완전 연관 매핑(Fully Associative Mapping)**: 블록을 아무 칸에나 넣을 수 있게 열어 두는 대신 찾을 때 모든 이름표를 한꺼번에 비교하는 방식
- **집합 연관 매핑(Set-Associative Mapping)**: 인덱스로 집합 하나를 고른 뒤 그 안의 몇 개 웨이만 비교해 앞의 두 방식을 절충한 방식
- **주소 분해기(Address Decoder)**: 들어온 주소를 태그·인덱스·오프셋으로 잘라 각 회로에 나눠 보내는 회로
- **태그 배열(Tag Array)·데이터 배열(Data Array)**: 각 라인의 블록 식별자와 상태를 담아 두는 쪽이 태그 배열, 실제 데이터를 담아 두는 쪽이 데이터 배열이다
- **축출(Eviction)·리필(Refill)**: 새 블록 자리를 만들려고 기존 라인을 내보내는 동작이 축출, 미스 난 블록을 아래 계층에서 받아 채우는 동작이 리필이다
- **교체 정책(Replacement Policy)**: 후보 웨이가 전부 찼을 때 어느 라인을 축출할지 고르는 규칙
- **1단계·2단계 캐시(L1·L2 Cache)**: ‘엘 원·엘 투’로 읽고 Level과 계층 번호를 줄인 표기이며, L1은 코어에 가장 가깝고 L2는 그 아래에서 더 큰 용량으로 미스를 받는다
- **마이크로컨트롤러(Microcontroller Unit, MCU)**: ‘엠씨유’로 읽고 영문 머리글자를 딴 약어이며, 프로세서·메모리·주변 장치를 한 칩에 담은 제어용 장치다

## Ⅰ. 개요

- 정의/개념: 메모리 블록의 캐시 배치·탐색 범위를 정해 적중을 판정하는 **매핑 구조**
- 기존 한계: 배치 규칙 없이는 캐시 내 **블록 위치 탐색 불가**

### 쉽게 이해하기 (학습용)

- 사물함에 짐을 아무 데나 던져 넣어 두면 찾을 때마다 문을 전부 열어 봐야 하는데, 답안이 배경 자리에 이 못 찾음을 적은 이유는 캐시가 빠른 이유가 메모리가 빨라서가 아니라 어디를 봐야 하는지를 주소만 보고 즉시 좁힐 수 있어서이기 때문이다

## Ⅱ. 특징

- 블록이 들어갈 **후보 웨이 수**가 곧 연관도
- **적중 시간·미스율**·미스 페널티로 **AMAT** 결정
- 주소 **충돌 집중도**가 높을수록 커지는 연관도 증가 효과

### 쉽게 이해하기 (학습용)

- 캐시를 평가할 때 적중률 하나만 보면 틀리는 이유가 둘째 줄에 있는데, 후보 칸을 늘려 헛걸음 비율을 낮춰도 매번 이름표를 더 많이 비교하느라 한 번의 조회가 길어지면 평균 대기 시간은 오히려 늘 수 있고, 게다가 방금 쓴 물건을 다시 찾는 습관이 없는 프로그램에서는 칸을 늘려도 헛걸음이 줄지 않는다

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    subgraph CC["캐시 제어기"]
        A[주소 분해기] -->|인덱스·태그| T[태그 탐색부]
        A -->|오프셋| D[데이터 배열]
        T -->|일치 웨이| D
        T -->|미스| R[교체 제어부]
        R -->|축출 웨이| D
        R -. 상태 갱신 .-> T
    end
```

| 설계 요소 | 설명 |
|:---|:---|
| 주소 분해기 | **주소 필드**를 태그·인덱스·오프셋으로 분리 |
| 태그 탐색부 | 인덱스로 집합 선택 후 **태그 배열** 비교 |
| 데이터 배열 | 일치 웨이와 오프셋 기준 **데이터 반환** |
| 교체 제어부 | 미스 시 **축출 웨이** 선정과 상태 갱신 |

> 요약: 인덱스는 **집합**, 태그는 **웨이**, 오프셋은 바이트를 각각 지목

### 쉽게 이해하기 (학습용)

- 주소 하나가 세 갈래로 잘려 나가는 것이 그림의 핵심인데, 잘린 세 조각이 각각 다른 회로로 곧장 들어가 어느 서랍장인지·그 안 어느 칸인지·그 칸의 몇 번째 자리인지를 동시에 좁히므로 세 번 물어보지 않고 한 번에 물건 앞에 설 수 있다

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant P as 요청 프로세서
    participant A as 주소 분해기
    participant T as 태그 탐색부
    participant D as 데이터 배열
    participant R as 교체 제어부
    participant M as 하위 메모리
    P->>A: 캐시 주소 요청
    A->>T: 인덱스·태그 전달
    T->>T: 유효 비트·태그 비교
    alt 적중
        T->>D: 적중 웨이 전달
        D-->>P: 캐시 데이터 반환
    else 미스
        T->>R: 미스 통보
        R->>M: 블록 리필 요청
        M-->>R: 리필 블록 반환
        R->>D: 데이터 배열 적재
        R->>T: 태그·상태 갱신
        D-->>P: 리필 데이터 반환
    end
```

| 절차 | 설명 |
|:---|:---|
| 캐시 주소 요청 | 프로세서가 읽기·쓰기 **메모리 주소** 전달 |
| 인덱스·태그 전달 | 매핑 방식이 정한 **탐색 범위** 지정 |
| 유효 비트·태그 비교 | 후보 웨이의 **적중 여부** 판정 |
| 적중 웨이 전달 | 일치 웨이의 **오프셋 위치** 데이터 반환 |
| 캐시 데이터 반환 | 적중한 라인의 요청 데이터를 프로세서에 반환 |
| 미스 통보 | **교체 정책** 기준 축출 웨이 선정 요청 |
| 블록 리필 요청 | 하위 계층에 **캐시 라인** 단위 요청 |
| 리필 블록 반환 | 하위 메모리가 요청한 **캐시 라인** 반환 |
| 데이터 배열 적재 | 리필 블록을 선정한 **축출 웨이**에 기록 |
| 태그·상태 갱신 | 새 블록의 태그·**유효 비트** 기록 |
| 리필 데이터 반환 | 적재한 라인의 요청 데이터를 프로세서에 반환 |

> 요약: 후보 범위가 좁을수록 **비교 단계**는 짧고 미스 위험은 상승

### 쉽게 이해하기 (학습용)

- 미스일 때만 아래 세 줄이 붙는 구조가 곧 캐시의 비용 구조인데, 적중이면 두세 걸음에 끝나지만 한 번 헛걸음하면 자리를 비우고 아래 계층까지 다녀와 채우는 세 걸음이 통째로 더 붙으므로 헛걸음 한 번의 값이 적중 여러 번의 값보다 크다



## Ⅴ. 종류 및 비교

| 캐시 매핑 방식 | 직접 매핑 | 완전 연관 매핑 | 집합 연관 매핑 |
|:---|:---|:---|:---|
| 적용 기준 | **적중 지연**을 최소로 눌러야 할 때 | 라인 수가 적은 소형 캐시일 때 | 미스율과 지연을 함께 봐야 할 때 |
| 핵심 특징 | 인덱스가 지정한 **단일 라인** 배치 | 전체 라인이 **단일 집합**인 배치 | 지정 집합의 **여러 웨이** 배치 |
| 한계 | 빈자리가 있어도 나는 **충돌 미스** | 전체 **태그 비교**의 면적·전력 폭증 | 웨이 선택·**교체 정책** 회로 부담 |

> 요약: 직접 매핑의 **충돌**과 완전 연관의 **비교 비용**을 집합 연관이 절충

### 쉽게 이해하기 (학습용)

- 세 칸이 이 순서로 놓인 이유는 앞 칸의 불편이 뒤 칸을 불러냈기 때문인데, 한 칸으로 못 박으니 옆 칸이 비어도 짐이 서로 밀어내고, 그래서 아무 칸이나 쓰게 열었더니 찾을 때마다 이름표를 전부 읽어야 했으며, 결국 네 칸짜리 묶음만 열어 두는 절충이 남았다

## Ⅵ. 실무 사례

1. 소형 **MCU** 캐시는 직접 매핑으로 적중 지연 최소화

### 쉽게 이해하기 (학습용)

- 제어용 소형 칩은 캐시 자체가 작아 이름표를 여러 개 비교할 회로를 넣을 자리도 없고 응답이 한 박자 늦는 것이 곧 제어 실패이므로, 후보를 한 칸으로 못 박아 조회를 가장 짧게 끝낸다

## Ⅶ. 결론

- 캐시 적중 향상을 위해 충돌 미스·비교 비용을 검토하여 **매핑** 활용

### 쉽게 이해하기 (학습용)

- 연관도는 높을수록 좋은 값이 아니라 넘기면 손해로 바뀌는 값이라, 웨이를 하나 더 늘려 줄어드는 헛걸음 손실이 늘어나는 비교 시간과 전력보다 큰 동안에만 올리고 그 지점에서 멈춘다
