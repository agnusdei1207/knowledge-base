## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 메모리(Cache Memory)**: CPU와 주기억장치 사이에 위치해 자주 접근하는 데이터 블록을 미리 보관해 접근 지연을 줄이는 고속 메모리.
- **캐시 매핑(Cache Mapping)**: 주기억장치 블록이 캐시 안의 어느 라인에 들어갈 수 있는지 결정하는 주소 사상 규칙.
- **캐시 라인(Cache Line)**: 캐시와 주기억장치 사이에서 한 번에 이동하는 데이터 단위이며, 태그·유효 비트·데이터 블록으로 구성.
- **태그(Tag)**: 요청한 주소의 상위 비트로, 캐시 라인에 적재된 블록이 찾는 블록과 일치하는지 판별하는 식별자.

</details>

- 정의/개념: 주기억장치 블록을 캐시 라인에 할당할 때 **태그와 인덱스 주소**를 기반으로 탐색하는 캐시 주소 사상 기법
- 배경/필요성: 동일 인덱스 참조 집중 시 발생하는 **충돌 미스(Conflict Miss)** 로 메모리 지연 급증

#### 한줄 요약
- 캐시 매핑은 메모리 블록이 캐시에서 앉을 수 있는 자리의 범위를 정하는 규칙으로, 자리가 좁으면 빠르지만 다른 블록과 자리 다툼이 잦아진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공간 지역성(Spatial Locality)**: 한 주소를 참조하면 인접 주소도 곧 참조될 가능성이 높은 성질로, 캐시가 라인 단위로 블록을 가져오는 근거.
- **시간 지역성(Temporal Locality)**: 최근 참조한 데이터가 다시 참조될 가능성이 높은 성질로, 캐시 적중률 향상의 근거.
- **충돌 미스(Conflict Miss)**: 캐시 용량이 남아도 같은 인덱스를 공유한 블록들이 서로 교체되어 발생하는 미스.
- **연관도(Set Associativity)**: 한 집합이 수용할 수 있는 캐시 라인 수이며, 높을수록 충돌 미스가 감소하나 비교 회로 비용이 증가.
- **AMAT(Average Memory Access Time)**: 평균 메모리 접근 시간으로, $AMAT = T_{hit} + Miss\,Rate \times Miss\,Penalty$로 산출.

</details>

- 라인 단위 반입으로 **공간 지역성** 활용
- 후보 라인 수(연관도)가 클수록 **충돌 미스** 감소·비교 회로 비용 증가의 상충
- 매핑 방식 선택은 $T_{hit}$·미스율·미스 패널티를 합산한 **AMAT** 판단

#### 한줄 요약
- 캐시는 인근 데이터를 함께 가져오는 습관을 이용하며, 매핑 방식은 자리 다툼이 얼마나 잦을지, 비교 회로 비용은 얼마나 드는지의 상충을 결정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 오프셋(Block Offset)**: 캐시 라인 내에서 요청 바이트 위치를 가리키는 주소 하위 비트.
- **집합 인덱스(Set Index)**: 집합 연관 캐시에서 후보 라인 집합을 선택하는 주소 중간 비트; 직접 매핑에서는 라인 인덱스로 사용.
- **유효 비트(Valid Bit)**: 캐시 라인에 사용 가능한 데이터가 적재돼 있음을 나타내는 단일 상태 비트.
- **교체 정책(Replacement Policy)**: 집합이 가득 찼을 때 새 라인을 위해 방출할 라인을 고르는 규칙(LRU, FIFO 등).

</details>

```text
[주소]
├─ 태그           ← 라인 일치 판별
├─ 집합 인덱스    ← 후보 집합 선택
└─ 블록 오프셋    ← 라인 내 위치 선택

[캐시 라인]
├─ 유효 비트
├─ 태그
├─ 데이터 블록
└─ 교체 상태
```

선의 의미: 가지는 포함 관계; 주소 필드와 라인 구성요소의 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 태그 | 적재 블록과 요청 블록의 **일치 판별** |
| 집합 인덱스 | 후보 라인 집합 선택 |
| 블록 오프셋 | 라인 내 요청 바이트 위치 선택 |
| 유효 비트 | 라인 데이터의 사용 가능 여부 표시 |
| 데이터 블록 | 주기억장치에서 반입한 라인 단위 데이터 보관 |
| 교체 상태 | 미스 시 방출할 **희생 라인** 선택 근거 보관 |

#### 한줄 요약
- 주소는 어느 집합을 볼지, 집합 안에서 태그가 맞는지, 라인 안에서 어느 바이트인지의 세 질문에 순서대로 답하며 데이터를 찾아간다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 적중(Cache Hit)**: 태그 비교가 성공해 캐시 라인에서 데이터를 바로 반환하는 상황.
- **캐시 미스(Cache Miss)**: 태그 불일치 또는 유효 비트 미설정으로 주기억장치에서 라인을 반입해야 하는 상황.
- **희생 라인(Victim Line)**: 새 라인 반입을 위해 교체 정책에 따라 방출되는 기존 캐시 라인.

</details>

```text
주소 입력
   │
   ▼
[ 1. 인덱스 기반 집합 선택 ]
   │
   ▼
[ 2. 태그 일치 판별 및 적중 처리 ]
   │
   ├─ 일치 → 블록 오프셋으로 데이터 즉시 반환
   │
   └─ 불일치/무효 → [ 3. 미스 반입 및 희생 라인 교체 ]
                           │
                           ▼
                     주기억장치 반입 및 태그·유효 비트 갱신
```

**동작 원리**

1. **인덱스 기반 집합 선택**: 주소의 집합 인덱스로 후보 라인 집합 접근
2. **태그 일치 판별 및 적중 처리**: 유효 비트와 태그 일치 시 오프셋 데이터 반환
3. **미스 반입 및 희생 라인 교체**: 주기억장치에서 반입 후 교체 정책으로 적재

#### 한줄 요약
- 캐시는 먼저 인덱스로 자리를 좁히고 태그 이름표를 맞춰 바로 내주거나, 없으면 오래된 라인을 내보내고 메모리에서 블록 한 줄을 새로 가져온다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 매핑(Direct Mapping)**: 블록당 후보 라인이 정확히 1개인 매핑 방식.
- **완전 연관 매핑(Fully Associative Mapping)**: 모든 캐시 라인이 후보가 되는 매핑 방식.
- **집합 연관 매핑(Set Associative Mapping)**: 캐시를 집합으로 나누고 집합 내 N개 라인이 후보가 되는 매핑 방식(N-way).

</details>

| 매핑 방식 | 직접 매핑 | 집합 연관 매핑 | 완전 연관 매핑 |
|:---|:---|:---|:---|
| 적용 기준 | 단순 구조·최단 적중 경로가 우선이고 충돌 미스 허용 가능 | 충돌 미스 완화와 구현 비용 균형이 필요 | 소용량 구조에서 충돌 미스 배제 요구 |
| 핵심 특징 | 블록당 후보 라인 1개로 **태그 비교** 최소 | N-way 집합 내 **연관도** 조정으로 충돌 완화 | 모든 라인이 후보·최대 유연성 |
| 한계 | 동일 인덱스 블록 간 **충돌 미스** 불가피 | Way 수 증가에 따른 태그 비교 회로·전력 증가 | 전역 태그 병렬 탐색 비용으로 대용량 적용 제약 |

#### 한줄 요약
- 직접 매핑은 지정 좌석 하나, 완전 연관은 전체 빈 좌석 어디든, 집합 연관은 정해진 구역 안의 몇 자리 중 선택하는 방식이며, 현대 CPU는 충돌과 비용의 균형점인 집합 연관을 표준으로 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인덱스 해싱(Index Hashing)**: 주소 비트를 XOR 조합해 특정 집합으로 요청이 쏠리는 핫 집합 현상을 완화하는 기법.
- **비차단 캐시(Non-blocking Cache)**: 한 미스가 처리 중이어도 독립적인 적중·미스 요청을 병렬 처리할 수 있는 캐시 구조.
- **MSHR(Miss Status Holding Register)**: 진행 중인 미스 요청과 이후 대기 요청을 추적해 비차단 캐시를 가능하게 하는 레지스터.
- **프리페치(Prefetch)**: 공간 지역성 예측을 바탕으로 미래 참조 가능성이 높은 라인을 미리 반입하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 핫 블록이 같은 집합에 집중해 **충돌 미스** 반복 | 연관도 증가 또는 인덱스 해싱으로 집합 분산 | 충돌 미스율 감소·반복 반입 감소 |
| 연관도 증가로 **태그 비교** 회로 전력 급등 | Way 예측 및 선택적 Way 활성화 적용 | $T_{hit}$ 유지하며 전력 절감 |
| 미스 처리 중 독립 요청이 대기 상태로 정지 | **MSHR** 기반 비차단 캐시 도입 | 메모리 수준 병렬성 향상 |
| 과도한 **프리페치**로 유용한 라인 조기 방출 | 적중률·오염도·대역폭 기준 프리페치 정책 조정 | 불필요한 반입 감소·유효 라인 보호 |

#### 한줄 요약
- 캐시 설계는 연관도만 높이는 문제가 아니라 핫 집합, 비차단 처리, 프리페치 오염을 함께 통제해야 실질적인 AMAT 이득을 얻는다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **적중 시간(Hit Time)**: 캐시에 데이터가 있을 때 요청부터 반환까지 걸리는 시간.
- **미스 패널티(Miss Penalty)**: 캐시 미스 후 주기억장치에서 라인을 반입하는 데 추가로 소요되는 시간.

</details>

- 충돌 미스 완화는 **집합 연관 매핑**, 최단 적중 지연은 **직접 매핑** 선택

#### 한줄 요약
- 가장 좋은 캐시 매핑은 가장 유연한 방식이 아니라, 실제 워크로드의 충돌 손실과 태그 비교 회로 비용을 AMAT 기준으로 재서 선택한 방식이다.
