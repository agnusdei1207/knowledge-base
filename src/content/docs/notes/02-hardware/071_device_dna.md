## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디바이스 DNA(Device DNA / Fingerprint)**: 단말기의 하드웨어, 운영체제, 브라우저 환경, 네트워크 파라미터 등 수십 가지 특성값을 수집·조합하여 단말기를 고유하게 식별하는 프로파일링 기술.
- **위험 기반 인증(RBA, Risk-Based Authentication)**: 접속한 단말의 신뢰도와 위험 점수를 실시간 평가하여 위험도가 높을 때만 추가 인증(Step-up Auth)을 요구하는 적응형 보안 체계.

</details>

- 정의/개념: 단말기의 하드웨어/OS/브라우저/네트워크 복합 정보를 수집해 기기 고유 식별 프로파일을 생성하고 **위험 기반 인증(RBA)** 을 수행하는 보안 프로파일링 기술
- 배경/필요성: ID/PW 탈취 및 크리덴셜 스터핑 공격 급증에 따른 **비인가 단말의 부정 로그인 및 금융 이상 거래 위험** 직면

#### 한줄 요약
- 단말기의 화면, 브라우저, 폰트, 네트워크 등 수많은 복합 특성을 조합해 기기 고유의 디지털 지문을 만들어 해킹을 잡아낸다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다차원 특성 수집(Multi-Factor Fingerprinting)**: OS 버전, CPU 코어 수, Canvas 렌더링 해시, WebGL 셰이더 결과, 설치된 폰트, 타임존 등을 결합하는 방식.
- **이상금융거래탐지시스템(FDS, Fraud Detection System)**: 디바이스 DNA와 거래 패턴을 머신러닝으로 분석해 보이스피싱 및 계정 도용을 실시간 차단하는 보안 시스템.

</details>

- 쿠키나 고정 IP를 삭제해도 단말기를 추적 가능한 **무상태(Stateless) 고유 식별**
- 단말기 신뢰도에 따른 **적응형 추가 인증(Step-up Authentication)** 연동
- 사용자가 별도의 보안 프로그램을 설치할 필요 없는 **무설치 웹 브라우저 기반 분석**

#### 한줄 요약
- 쿠키를 지워도 기기 자체의 특성으로 식별하며, 평소 쓰던 기기가 아닐 때만 OTP나 생체 인증을 추가로 요구한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Canvas 핑거프린팅**: 브라우저에서 보이지 않는 그래픽을 렌더링할 때 GPU와 그래픽 드라이버의 미세한 픽셀 차이를 해시화하여 기기를 구별하는 기법.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ Device DNA 수집 및 이상 거래 탐지(FDS/RBA) 아키텍처        │
│                                                             │
│  [ 사용자 단말기 (스마트폰 / PC 웹 브라우저) ]              │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 클라이언트 수집 모듈 (JS SDK / Native SDK)            │  │
│  │  ├─ 하드웨어 정보 (CPU/메모리/화면 해상도/배터리 API)  │  │
│  │  ├─ 소프트웨어 정보 (OS 버전/Canvas 해시/WebGL/폰트)   │  │
│  │  └─ 네트워크 정보 (IP 대역/VPN 여부/타임존/User-Agent)│  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             ▼ (암호화 전송)                 │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 디바이스 DNA 분석 서버 (FDS / RBA 엔진)               │  │
│  │  ┌───────────────────────┐ ┌───────────────────────┐  │  │
│  │  │ 특성 정규화 & 해싱    │ │ 기기 식별 프로파일러  │  │  │
│  │  └───────────┬───────────┘ └───────────┬───────────┘  │  │
│  │              ▼                         ▼              │  │
│  │  ┌─────────────────────────────────────────────────┐  │  │
│  │  │ 위험 점수(Risk Score) 산출 & AI 이상 탐지       │  │  │
│  │  └───────────────────────┬─────────────────────────┘  │  │
│  └──────────────────────────┼────────────────────────────┘  │
│                             ▼                               │
│  [ 정책 실행 ] ──► [ 정상 승인 / 추가 2차 인증(MFA) / 접속 차단 ] │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 클라이언트 SDK가 단말 특성을 수집해 서버로 전송하면, FDS 엔진이 과거 프로파일과 비교하여 인증 정책을 집행

| 구성요소 | 책임 |
|:---|:---|
| 클라이언트 수집 SDK | Canvas, WebGL, 폰트, 오디오 컨텍스트 등 수십 가지 브라우저 특성 추출 |
| 특성 정규화 엔진 | 브라우저 업데이트 등으로 인한 경미한 파라미터 변화를 정규화 및 가중치 해시 변환 |
| 기기 식별 프로파일러 | 추출된 해시값을 기존 사용자 기기 히스토리와 비교하여 유사도 매칭(Matching) |
| RBA 위험 분석 엔진 | 접속 IP 지리적 위치, VPN 우회 여부, 이전 거래 패턴을 종합해 위험 스코어 산출 |
| 적응형 인증 정책기 | 점수가 안전하면 패스, 의심스러우면 SMS/앱 푸시 추가 인증(Step-up), 위험 시 즉각 차단 |

#### 한줄 요약
- 수집 SDK, 정규화 엔진, 기기 프로파일러, RBA 위험 분석기, 인증 정책기가 실시간 보안 결정을 내린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **핑거프린트 유사도 매칭(Similarity Matching)**: OS 업데이트 등으로 핑거프린트 일부가 바뀌어도 자카드(Jaccard) 유사도 등으로 동일 기기임을 판별하는 기법.

</details>

```text
사용자 로그인 또는 금융 이체 요청
      │
      ▼
1. 단말 정보 수집: JS SDK가 Canvas 렌더링, WebGL, 화면 스펙 등 50여 종 데이터 추출
      │
      ▼
2. Device DNA 생성: 수집된 파라미터를 SHA-256 알고리즘으로 압축해 기기 해시 생성
      │
      ▼
3. 프로파일 대조: 데이터베이스 내 해당 사용자의 기등록 단말 프로파일과 유사도 계산
      │
      ▼
4. 위험 평가: 이상 징후(신규 기기, 해외 IP, 비정상 결제 시간) 종합 위험 점수 산출
      ├── [안전: 평소 기기] ──► 5-1. 무자각(Zero-friction) 즉시 로그인 승인
      ├── [의심: 변조 의심] ──► 5-2. 생체 인증 또는 OTP 추가 2차 인증(Step-up) 요구
      └── [위험: 블랙리스트]──► 5-3. 거래 즉각 차단 및 보안 관제 알림
```

**동작 원리**

1. **파라미터 추출**: 웹 접속 시 백그라운드 스크립트가 실행되어 하드웨어 및 렌더링 특성값 인출
2. **고유 지문 생성**: 클라이언트와 서버가 협력하여 조작 불가능한 디바이스 DNA 식별자 계산
3. **히스토리 비교**: 사용자가 과거 3개월간 사용했던 신뢰 단말 목록과 비교하여 일치율 산정
4. **리스크 스코어링**: 평소와 다른 기기이거나 매크로/VPN 환경일 경우 위험 점수를 대폭 상향
5. **적응형 정책 집행**: 안전한 기기는 비밀번호만으로 통과시키고, 낯선 기기는 강력한 MFA 강제

#### 한줄 요약
- 특성 추출 → Device DNA 해시 생성 → 히스토리 대조 → 위험도 산정 → 적응형 차등 인증 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 단말 식별 및 인증 기술 | Device DNA (소프트웨어 지문) | PUF (하드웨어 반도체 지문) | MAC / IMEI (정적 식별자) | FIDO2 (생체 기반 공개키) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 웹/앱 무설치 금융 이상 거래 탐지 | 물리적 반도체 칩 복제 방지 | 폐쇄망 네트워크 장비 등록 | 사용자 주도 패스워드리스 생체 인증 |
| 핵심 특징 | 브라우저/OS 복합 정보 기반 확률적 식별 | 실리콘 공정 편차 기반 결정론적 키 생성 | 하드웨어 고유 번호 직접 읽기 | 기기 내부 보안 칩에 개인키 저장 서명 |
| 한계 | 브라우저 업데이트 시 지문 변동(Drift) | 전용 보안 반도체 칩 설계 필요 | OS 권한 제한 및 스푸핑(위조) 용이 | 사용자 인터랙션(지문 터치 등) 필수 |

#### 한줄 요약
- 웹 이상 거래 탐지는 Device DNA, 칩 하드웨어 보안은 PUF, 정적 식별은 MAC, 생체 인증은 FIDO2를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핑거프린트 드리프트(Fingerprint Drift)**: 브라우저 자동 업데이트나 드라이버 패치로 인해 정상 기기의 식별 파라미터가 서서히 바뀌는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 브라우저 업데이트로 인한 **핑거프린트 드리프트 및 오탐(False Positive)** | **퍼지 가중치 매칭(Fuzzy Matching)** 및 점진적 프로파일 자동 갱신 | 정상 사용자 차단 방지 및 UX 유지 |
| 다크웹 해킹 도구를 통한 **Canvas/User-Agent 지문 위조(Spoofing)** | 브라우저 일관성 검증(헤더 vs JS 환경 정합성) 및 행동 바이오메트릭스 결합 | 위조 브라우저 및 봇넷 공격 100% 탐지 |
| 과도한 개인정보 수집으로 인한 **프라이버시 규제(GDPR/개인정보보호법) 위반** | 개인 식별 정보(PII) 배제 및 **원방향 단방향 해시 암호화 저장** | 컴플라이언스 준수 및 개인정보 유출 방지 |
| VPN 및 프록시 우회 접속을 통한 **IP 세탁 이상 거래** | **IP 평판 DB 연동** 및 WebRTC 로컬 IP 역추적 기법 병행 | 우회 접속 탐지 및 고위험군 격리 |

#### 한줄 요약
- 퍼지 매칭으로 오탐을 줄이고, 일관성 검증으로 위조를 잡으며, 단방향 해시로 개인정보를 보호한다.

## Ⅶ. 결론

- 온라인 뱅킹, 전자상거래, 이상금융거래탐지(FDS) 구축 시 **Device DNA 기반 무자각 위험 평가와 FIDO2 결합** 필수

#### 한줄 요약
- 소프트웨어 복합 핑거프린팅을 통해 사용자의 불편 없이 비인가 단말과 부정 거래를 정밀하게 사전 차단해야 한다.
