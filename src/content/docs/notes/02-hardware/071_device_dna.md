## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디바이스 DNA(Device DNA / Fingerprint)**: 단말기의 하드웨어, 운영체제, 브라우저 환경, 네트워크 파라미터 등 수십 가지 특성값을 수집·조합하여 단말기를 고유하게 식별하는 프로파일링 기술.
- **위험 기반 인증(RBA, Risk-Based Authentication)**: 접속한 단말의 신뢰도와 위험 점수를 실시간 평가하여 위험도가 높을 때만 추가 인증(Step-up Auth)을 요구하는 적응형 보안 체계.

</details>

- 정의/개념: 단말의 하드웨어·OS·브라우저·네트워크 특성을 조합해 프로파일을 만들고 이를 근거로 **위험 기반 인증(RBA, Risk-Based Authentication)**을 수행하는 **디바이스 DNA(Device DNA / Fingerprint)**
- 배경/필요성: 자격 증명이 이미 유출됐다는 전제에서는 아이디·비밀번호만으로 정상 사용자를 구분할 수 없어 접속 단말 자체를 근거로 삼아야 함

#### 한줄 요약
- 이 기술은 사용자를 확인하는 대신 낯선 상황을 찾아내는 쪽으로 방향을 바꾼 것이며, 그래서 결론이 참·거짓이 아니라 확률로 나온다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다차원 특성 수집(Multi-Factor Fingerprinting)**: OS 버전, CPU 코어 수, Canvas 렌더링 해시, WebGL 셰이더 결과, 설치된 폰트, 타임존 등을 결합하는 방식.
- **이상금융거래탐지시스템(FDS, Fraud Detection System)**: 디바이스 DNA와 거래 패턴을 머신러닝으로 분석해 보이스피싱 및 계정 도용을 실시간 차단하는 보안 시스템.

</details>

- **다차원 특성 수집(Multi-Factor Fingerprinting)**으로 쿠키 없이도 확률적 기기 식별
- 단말 신뢰도에 따라 추가 인증을 선택적으로 요구하는 적응형 정책 연동
- 별도 설치 없이 브라우저·앱 환경에서 수집 가능해 도입 마찰이 낮음

#### 한줄 요약
- 확률적 판정이기 때문에 임계값을 올리면 정상 사용자가 막히고 내리면 공격이 통과하므로, 이 기술의 품질은 정확도가 아니라 임계값 운영에서 갈린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Canvas 핑거프린팅**: 브라우저에서 보이지 않는 그래픽을 렌더링할 때 GPU와 그래픽 드라이버의 미세한 픽셀 차이를 해시화하여 기기를 구별하는 기법.

</details>

```text
[디바이스 DNA 판정 구조]
├─ 사용자 단말
│  └─ 수집 모듈
│     ├─ 하드웨어 특성 (해상도·코어 수·센서)
│     ├─ 소프트웨어 특성 (OS 버전·렌더링 해시·설치 폰트)
│     └─ 네트워크 특성 (IP 대역·타임존·클라이언트 정보)
└─ 분석 서버
   ├─ 특성 정규화·해싱
   ├─ 기기 식별 프로파일러 (과거 이력 대조)
   ├─ 위험 점수 산출 엔진
   └─ 적응형 인증 정책기 (승인·추가 인증·차단)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 단말은 특성을 내보낼 뿐 판정은 전부 서버 쪽에서 이뤄짐

| 구성요소 | 책임 |
|:---|:---|
| 수집 모듈 | **Canvas 핑거프린팅**을 포함한 다수 환경 특성 추출 |
| 특성 정규화 엔진 | 사소한 파라미터 변화를 흡수하고 가중치 부여 |
| 기기 식별 프로파일러 | 기존 이력과 대조해 동일 기기 여부 추정 |
| 위험 점수 엔진 | 위치·우회 여부·거래 맥락을 종합해 위험도 산출 |
| 적응형 인증 정책기 | 위험 구간별로 통과·추가 인증·차단 결정 |

#### 한줄 요약
- 판정 로직이 전부 서버에 있기 때문에 공격자가 단말에서 수집 값을 조작할 수 있으며, 서버는 그 값이 참인지가 아니라 서로 모순되지 않는지를 본다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **핑거프린트 유사도 매칭(Similarity Matching)**: OS 업데이트 등으로 핑거프린트 일부가 바뀌어도 자카드(Jaccard) 유사도 등으로 동일 기기임을 판별하는 기법.

</details>

```text
로그인·이체 요청 → 단말 특성 추출 후 정규화
        │
   기존 기기 이력과 유사도가 충분한가?
   ┌────┴─────┐
  예           아니오
   │             │
익숙한 기기로   신규·변조 가능성으로 가중
판정             │
   └────┬────────┘
        │
   위치·행동·거래 맥락을 합산해 위험 점수 산출
        │
   위험 구간은 어디인가?
   ┌────┼──────┐
낮음     중간     높음
 │        │       │
기존 흐름  추가 인증  거래 보류·관제 검토
```

분기 결과: 기기 유사도 하나로 결론을 내리지 않고 맥락 신호와 합산하는 구조라, 지문이 바뀌어도 다른 신호가 정상이면 통과할 여지가 남음

#### 한줄 요약
- **핑거프린트 유사도 매칭(Similarity Matching)**을 쓰는 순간 판정은 이분법을 벗어나며, 이 여유가 오탐을 줄이는 동시에 공격자에게도 여지를 남긴다.

## Ⅴ. 종류 및 비교

| 단말 식별 및 인증 기술 | Device DNA (소프트웨어 지문) | PUF (하드웨어 반도체 지문) | MAC / IMEI (정적 식별자) | FIDO2 (생체 기반 공개키) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 웹/앱 무설치 금융 이상 거래 탐지 | 물리적 반도체 칩 복제 방지 | 폐쇄망 네트워크 장비 등록 | 사용자 주도 패스워드리스 생체 인증 |
| 핵심 특징 | 브라우저/OS 복합 정보 기반 확률적 식별 | 실리콘 공정 편차 기반 결정론적 키 생성 | 하드웨어 고유 번호 직접 읽기 | 기기 내부 보안 칩에 개인키 저장 서명 |
| 한계 | 브라우저 업데이트 시 지문 변동(Drift) | 전용 보안 반도체 칩 설계 필요 | OS 권한 제한 및 스푸핑(위조) 용이 | 사용자 인터랙션(지문 터치 등) 필수 |

#### 한줄 요약
- 네 기술은 식별 근거가 소프트웨어 환경·물리 소자·고정 번호·개인키로 갈리며, 위조 난도가 올라갈수록 사용자 참여나 전용 하드웨어라는 대가가 따른다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핑거프린트 드리프트(Fingerprint Drift)**: 브라우저 자동 업데이트나 드라이버 패치로 인해 정상 기기의 식별 파라미터가 서서히 바뀌는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 업데이트로 **핑거프린트 드리프트(Fingerprint Drift)** 발생 | 가중치 기반 유사도 매칭과 점진적 프로파일 갱신 | 정상 사용자 차단 방지와 사용성 유지 |
| 수집 값 위조로 다른 기기인 척 위장 | 헤더·스크립트·행동 특성의 정합성 교차 검증 | 단일 특성 위조에 대한 탐지력 향상 |
| 과도한 특성 수집으로 프라이버시 침해 | 목적·보유 기간 최소화와 가명처리·삭제 절차 적용 | 재식별과 장기 추적 위험 감소 |
| 우회 접속으로 위치 신호가 무력화 | 주소 평판을 단독 근거로 쓰지 않고 다른 신호와 결합 | 정상 우회 사용자 오탐과 공격 미탐의 절충 |

#### 한줄 요약
- 식별력을 높이려면 더 많은 특성을 모아야 하고 프라이버시를 지키려면 덜 모아야 하므로, 이 기술의 상한은 기술이 아니라 규제와 사회적 수용도가 정한다.

## Ⅶ. 결론

- 계정 탈취 위험이 큰 서비스는 디바이스 DNA를 단독 판단 근거가 아닌 보조 신호로 쓰고 강한 인증 수단·거래 맥락과 결합하며, 임계값을 정할 때 오탐과 지문 변동, 프라이버시 영향까지 함께 반영

#### 한줄 요약
- 이 방식은 확실한 차단을 제공하지 않고 의심 구간을 좁혀 줄 뿐이므로, 최종 결정은 언제나 다른 인증 수단이나 사람이 맡아야 한다.
