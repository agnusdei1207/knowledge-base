## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Device DNA(디바이스 DNA)**: 단말의 하드웨어 스펙, OS/브라우저 환경, 네트워크 파라미터 및 사용자 행태적 특성을 융합하여 생성한 고유한 복합 기기 지문(Device Fingerprint).
- **Device Fingerprinting(장치 지문화)**: 특정 에이전트나 센서를 통해 단말의 수십 가지 세부 속성을 비침습적으로 수집·추출하는 기술.
- **Static Identifier(정적 식별자)**: MAC 주소, IMEI, IP 주소 등 단일 문자열로 구성되어 손쉽게 위변조(Spoofing)될 수 있는 기존 식별자.

</details>

- 정의/개념: 단말의 하드웨어 고유 특성, 소프트웨어 환경(OS/브라우저/글꼴), 네트워크 상태 및 사용자 행태 정보를 다차원 수집·결합하여 생성한 비침습적 복합 식별 프로파일(디지털 기기 지문)
- 배경/필요성: MAC, IMEI, IP 등 단일 정적 식별자의 위변조(Spoofing) 공격을 극복하고, **금융/핀테크 FDS(이상거래탐지시스템) 및 제로 트러스트 환경에서 위험 기반 적응형 인증(RBA) 수행**

#### 한줄 요약

- 단말의 다차원 HW/SW/행태 특성을 결합한 **동적 기기 지문 기반 위험 적응형 인증(RBA)**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Composite Attributes(복합 특성)**: CPU 코어 수, WebGL 렌더러, 시스템 폰트, 화면 해상도, 터치 가속도 등 다양한 계층의 속성 집합.
- **Similarity Score(유사도 점수)**: 이전 기준 프로파일과 현재 측정값 간의 코사인 유사도나 해밍 거리를 계산하여 본인 일치 확률(0~100%)을 도출하는 척도.
- **Drift Adaptation(드리프트 적응)**: OS 패치나 브라우저 업데이트로 인한 정상적인 기기 지문 변화를 추적하여 오탐을 방지하는 지속 학습 기법.

</details>

- 단일 식별자 스푸핑을 무력화하기 위해 HW/SW/네트워크 계층을 망라한 **다차원 복합 특성(Composite Attributes) 수집**
- 100% 일치(0/1) 여부가 아닌 확률적 매칭을 통해 위험도를 평가하는 **유사도 점수(Similarity Score) 기반 판정**
- 정상적인 펌웨어 갱신이나 설정 변경에 따른 지문 변화를 수용하는 **동적 드리프트(Drift) 적응 알고리즘**

#### 한줄 요약

- **다차원 복합 특성 결합·유사도 점수(Similarity Score) 위험 판정·환경 변화 드리프트(Drift) 적응**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Feature Collector(특성 수집기)**: 브라우저/앱 단에서 Canvas 렌더링, 오디오 컨텍스트, 배터리 API, 폰트 목록 등을 수집하는 모듈.
- **DNA Profile Generator(프로파일 생성기)**: 수집된 이종 파라미터를 정규화(Normalization)하고 특징 벡터로 변환하여 해시화하는 엔진.
- **Risk-Based Scoring Engine**: Baseline DNA와 비교하여 위험 점수(Risk Score)를 산출하고 다단계 인증(MFA) 트리거 여부를 결정하는 평가기.

</details>

```text
[ Device DNA 다차원 특성 수집 및 위험 기반 인증 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 특성 수집기 (HW 사양, WebGL 캔버스, 폰트, 터치 행태)    │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 미가공 텔레메트리 데이터 ]
┌──────────────────────────────┴──────────────────────────────┐
│ 2. DNA 프로파일 생성 엔진 (정규화 ──> 특징 벡터 ──> 지문 해싱)│
└──────┬───────────────────────────────────────────────┬──────┘
       │ [ 현재 측정 DNA 지문 ]                        │ [ Baseline DNA ]
┌──────▼───────────────────────────────────────────────▼──────┐
│ 3. 유사도 비교 및 위험 채점 엔진 (Risk-Based Scoring Engine) │
│  ├─ 코사인 유사도 연산 및 드리프트(Drift) 이력 반영          │
│  └─ RBA 정책 판단 (Low: 허용, Med: Step-Up MFA, High: 차단) │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 특성 수집기(Collector), DNA 프로파일 생성 엔진(Hasher), 기준 DNA 저장소 및 유사도 비교/위험 채점 엔진(RBA) 간의 Device DNA 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 특성 수집 | 폰의 CPU, 램, 브라우저 폰트, 심지어 타자 치는 속도까지 영혼까지 끌어모아 탈탈 터는 정보 수집기 |
| 디엔에이 프로파일 생성 | 수집한 잡다한 데이터를 수학적으로 짓이겨서 해싱하고 고유한 벡터 지문으로 찍어내는 공장 |
| 기준 DNA 저장소 | 진짜 주인의 예전 지문(Baseline)과 나이 들면서 변한 궤적(**드리프트** 이력)을 보관하는 금고 |
| 유사도 비교 위험 판정 | 방금 찍힌 지문이랑 금고 지문을 비교해서, 짭인지 찐인지 **유사도 점수**를 매겨 위험 수위를 판정하는 재판관 |

#### 한줄 요약

- **특성 수집기(Collector)·DNA 프로파일 생성 엔진·기준 DNA 저장소·유사도/위험 채점 엔진**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Step-Up Authentication(승격 인증)**: 위험 점수가 의심 구간(Medium)에 도달했을 때 OTP나 생체 인증 등 2차 인증을 추가 요구하는 정책.

</details>

```text
[ Device DNA 생성 및 위험 기반 인증(RBA) 시퀀스 ]
                         │
                         ▼
   [ 1. 세션 난수(Nonce) 바인딩 및 브라우저/단말 다차원 특성 수집 ]
                         │
                         ▼
   [ 2. 파라미터 벡터 정규화 및 단말 DNA 디지털 지문 프로파일 생성 ]
                         │
                         ▼
   [ 3. 사용자 기준 Baseline DNA 와 코사인 유사도 매칭 및 드리프트 반영 ]
                         │
        +─────────────────────────────────────────+
        │             [ 위험도(Risk Score) 판정 ]  │
        │             /            |            \ │
        │        [ 낮음 ]       [ 중간 ]       [ 높음 ]
        │           │              │              │
        │     4. 즉시 승인   4. 2차 인증 요구  4. 접근 차단
        │        (Seamless)     (Step-Up MFA)    및 FDS 경보
        +─────────────────────────────────────────+
```

**동작 원리**

1. **특성 수집**: 세션 재전송 방지를 위한 Nonce와 함께 브라우저/OS/HW 속성 텔레메트리 획득
2. **프로파일 연성**: 다차원 속성을 정규화된 비트 벡터로 인코딩하고 암호학적 해시를 적용해 기기 지문 생성
3. **유사도 대조**: 저장된 과거 정상 지문 및 드리프트 변동 이력과의 일치율(Similarity Score) 계산
4. **위험 기반 분기**:
   - 유사도 95% 이상 (Risk Low): 무자각 무마찰(Seamless) 로그인 허용
   - 유사도 70~94% (Risk Med): 폰트/OS 변경 의심으로 SMS/OTP 추가 인증 요구
   - 유사도 70% 미만 (Risk High): 기기 위변조 스푸핑으로 간주하여 세션 즉시 차단

#### 한줄 요약

- 단말 특성 수집 $\to$ **특성 벡터 정규화 & 해싱 $\to$ 기준 DNA 유사도 비교 $\to$ 위험도 스코어링 $\to$ RBA 정책 분기(허용/2차 인증/차단)**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Device DNA vs PUF vs Static ID**:
  - Device DNA: HW/SW/행태 복합 수집, 소프트웨어 FDS/RBA, 확률적 유사도
  - PUF: 반도체 실리콘 흠집, 하드웨어 비밀키 재생, 결정론적 0/1
  - Static ID: MAC/IMEI 단순 문자열, 복제/변조 취약

</details>

| 비교 항목 | Device DNA (복합 장치 지문) | PUF (물리적 복제 불가 함수) | Static Identifier (정적 고정 식별자) |
|:---|:---|:---|:---|
| 데이터 원천 및 추출 | HW 사양 + OS/SW 설정 + 사용자 행동 (소프트웨어적 수집) | 반도체 공정 미세 편차 (하드웨어 실리콘 회로) | MAC 주소, IMEI, IP, 쿠키 ID (설정 파일/레지스터) |
| 인증 방식 및 판정 | 확률적 유사도 점수 기반 RBA (다계층 위험 판정) | 결정론적 암호키 재생 및 서명/복호화 (0/1 판정) | 1:1 문자열 단순 일치 비교 (True/False) |
| 한계 및 보안 위협 | 환경 업데이트 시 드리프트 오탐 가능, 파라미터 변조 | 전용 PUF 회로 하드웨어 필요, 모델링 공격 | 스푸핑 및 복제 위조에 완전히 취약 |

#### 한줄 요약

- 복합 FDS는 **Device DNA**, 하드웨어 암호키는 **PUF**, 단순 인벤토리는 **Static ID**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Session Binding**: Device DNA 생성 시 서버가 발급한 일회용 난수(Session Nonce)를 서명에 결합하여 도난당한 지문의 재전송(Replay) 공격을 원천 차단하는 기법.
- **Data Minimization(개인정보 최소 수집)**: GDPR 및 개인정보보호법 준수를 위해 PII(개인식별정보)를 배제하고 기기 렌더링/환경 해시값만을 수집하는 원칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 주인이 폰을 펌웨어 업데이트했더니 지문이 바뀌어서 해커로 오해받고(**오탐**) 접속이 영구 차단되는 환장할 사태 | 시간이 지남에 따라 지문이 변하는 **드리프트** 곡선을 반영하고 임계치를 유들유들하게 가변 조정 수행 | 진짜 주인이 오탐으로 블록 먹는 억울한 사태를 방지하고 정상 단말 생존율 100% 극한 보장 |
| 해커가 남의 폰 지문 파라미터를 통째로 복사해서 은행 앱에 들이미는 기만적인 지문 재전송 복붙 공격 발발 | 접속할 때마다 매번 바뀌는 일회용 난수(Nonce)를 섞어버리는 얄짤없는 **세션 바인딩** 융합 처리 강제 | 어제 훔친 지문을 오늘 다시 써먹으려는 재전송 스푸핑 공격을 100% 원천 셧다운 무력화 |
| 지문 만든다고 사용자의 위치, 연락처까지 영혼까지 다 털어갔다가 개인정보보호법(GDPR)에 쳐맞는 프라이버시 침해 | 법적 규제를 준수해 식별에 딱 필요한 비식별 정보만 털어가는 **최소 수집**과 얄짤없는 보관 기간 통제 | 과도한 개인정보 징수로 인한 회사 망할 수준의 철퇴 리스크 방어 및 프라이버시 절대 사수 |

#### 한줄 요약

- **정상 업데이트 드리프트(Drift) 학습 알고리즘·Session Nonce 바인딩(재전송 차단)·최소 수집(GDPR 준수)**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Zero Trust 엔드포인트 검증**: "Never Trust, Always Verify" 원칙에 따라 로그인 시점뿐만 아니라 세션 유지 중에도 주기적으로 Device DNA를 재검증(Continuous Adaptive Risk).

</details>

- 차세대 제로 트러스트 및 전자금융 보안에서 **하드웨어 RoT(PUF)와 소프트웨어 Device DNA(RBA)를 융합한 다계층 인증 표준 채택**

#### 한줄 요약

- **결정론적 하드웨어 키(PUF)와 확률적 복합 지문(Device DNA)**의 상호 보완적 통합
