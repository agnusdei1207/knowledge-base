## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디바이스 DNA(Device DNA / Device Fingerprint)**: 단말기의 하드웨어 렌더링 특성, OS 환경, 브라우저 엔진 설정, 네트워크 파라미터 등 수십 가지 복합 특성값을 수집·결합하여 단말기를 고유하게 식별하는 기기 프로파일링 기술.
- **위험 기반 인증(Risk-Based Authentication, RBA)**: 접속한 단말의 디바이스 DNA 신뢰도와 거래 위험 점수를 실시간 평가하여, 이상 징후 감지 시에만 2차 인증(MFA)을 요구하는 적응형 보안 체계.

</details>

- 정의/개념: 단말의 하드웨어·소프트웨어 다차원 특성을 비식별 수집하여 기기 고유 프로파일을 생성하고 **위험 기반 인증(RBA)**을 수행하는 **디바이스 DNA 기술**
- 배경/필요성: 쿠키 삭제, 시크릿 모드, 앱 재설치 등으로 인한 **기존 정적 식별자(Cookie, IMEI) 무력화 한계 및 비대면 금융 사기 위험**

#### 한줄 요약
- 디바이스 DNA는 쿠키나 고정 식별자 없이 수십 가지 단말 환경 특성을 결합하여 기기를 식별하고 FDS 위험 점수를 산출한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다차원 특성 결합(Multi-Factor Fingerprinting)**: 화면 해상도, CPU 코어 수, Canvas 렌더링 해시, WebGL 셰이더 결과, 설치 폰트 목록, 타임존 등을 결합하는 방식.
- **이상금융거래탐지시스템(Fraud Detection System, FDS)**: 디바이스 DNA와 금융 거래 패턴을 머신러닝으로 실시간 분석하여 사기 거래를 자동 차단하는 보안 시스템.

</details>

- 비침습적 무설치 수집: 별도 보안 프로그램 설치 없이 웹 표준 자바스크립트 스크립트만으로 다차원 특성 수집
- 쿠키 독립적 식별: 브라우저 쿠키 삭제나 시크릿 모드 접속 시에도 하드웨어/엔진 특성 기반 확률적 고유 식별 수행
- 적응형 보안 연계: 단말의 위험도(Risk Score)에 따라 정상 사용자는 통과시키고, 이상 접속 시에만 단계별 추가 인증(Step-up Auth) 요구

#### 한줄 요약
- 무설치 스크립트로 하드웨어 렌더링 특성을 수집해 쿠키 없이도 기기를 식별하며, FDS와 연계해 단계별 인증을 수행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Canvas 핑거프린팅(Canvas Fingerprinting)**: 브라우저 백그라운드에서 보이지 않는 2D 그래픽/텍스트를 렌더링할 때 GPU와 그래픽 드라이버의 서브픽셀 앤티에일리어싱 차이를 해시화하여 기기를 구별하는 기법.
- **WebGL 핑거프린팅**: GPU 모델명, 벤더 정보 및 3D 셰이더 연산 결과의 부동소수점 미세 오차를 추출하는 기법.

</details>

```text
+-------------------------------------------------------------------------------+
|                 디바이스 DNA 수집 및 FDS 위험 기반 인증 아키텍처              |
|                                                                               |
|  [ 클라이언트 단말 (Client Endpoint - 무설치 자바스크립트 수집) ]            |
|  +-------------------------------------------------------------------------+  |
|  | - 그래픽 렌더링 특성 : Canvas 2D 픽셀 해시, WebGL 셰이더 부동소수점 오차|  |
|  | - 하드웨어/시스템 특성: CPU 코어 수, 메모리 용량, 배터리 API, 화면 해상도|  |
|  | - 브라우저/네트워크  : 시스템 폰트, AudioContext 지문, IP/ASN, 타임존   |  |
|  +-------------------------------------------------------------------------+  |
|                                    │ HTTPS 암호화 전송 (JSON 페이로드)        |
|                                    ▼                                          |
|  [ 서버 측 FDS 분석 및 정책 엔진 (Server Engine) ]                            |
|  +-------------------------------------------------------------------------+  |
|  | 1. 특성 정규화 엔진 : 가중치 기반 단방향 퍼지 해시(Fuzzy Hash) 생성     |  |
|  +-------------------------------------------------------------------------+  |
|                                    │ 정규화된 디바이스 핑거프린트             |
|                                    ▼                                          |
|  +-----------------------------------+   +---------------------------------+  |
|  | 2. 기기 프로파일러 (Matcher)      |   | 3. 위험 점수 엔진 (Risk Scorer) |  |
|  | - 기등록 기기 DB 대조 (유사도 측정)|   | - 접속 국가, IP 평판, 금액 결합 |  |
|  +-----------------------------------+   +---------------------------------+  |
|                                    │     │                                    |
|                                    ▼     ▼ 종합 위험 점수 (0~100)             |
|  +-------------------------------------------------------------------------+  |
|  | 4. 적응형 정책기 (Adaptive Policy Engine)                                |  |
|  |    - 저위험: 무자각 즉시 승인 / 중위험: MFA 추가인증 / 고위험: 거래 차단  |  |
|  +-------------------------------------------------------------------------+  |
+-------------------------------------------------------------------------------+
```

- 신호 및 연결 관계: 클라이언트 브라우저에서 추출된 다차원 지문 데이터는 HTTPS를 통해 서버 엔진으로 전송되며, 특성 정규화와 프로파일 DB 매칭 및 위험 점수 결합(`▼`)을 통해 단계별 적응형 인증 정책을 집행함을 명시함

| 구성요소 | 책임 |
|:---|:---|
| 클라이언트 스크립트 | Canvas·WebGL 등 환경 특성 수집 |
| 특성 정규화 엔진 | 변화 완충과 퍼지 해시 생성 |
| 기기 프로파일러 | 유사도 기반 기기 매칭 |
| 위험 점수 엔진 | 접속·거래 맥락의 이상 탐지 |
| 적응형 정책기 | 승인·추가 인증·차단의 **RBA** 집행 |

#### 한줄 요약
- 단말에 식별자를 심어 두는 대신 접속할 때마다 환경 특성을 다시 모아 지문을 계산하므로 지우면 사라지는 저장물이 없어지고, 그 대가로 값이 조금씩 흔들리는 문제는 정규화기의 퍼지 해시와 프로파일러의 유사도 매칭이 떠맡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **핑거프린트 유사도 매칭(Similarity Matching)**: 브라우저 패치나 설정 변경으로 지문 일부가 변경되어도 가중치 기반 퍼지 알고리즘으로 기존 동일 기기임을 판별하는 기법.

</details>

```text
[전자금융 로그인 또는 송금 이체 요청 발생]
                    │
                    ▼
1. 클라이언트 스크립트: Canvas/WebGL 렌더링 및 50여 개 환경 특성 즉시 추출
                    │
                    ▼
2. FDS 수집 서버 전송 및 가중치 기반 퍼지 지문 해시 정규화
                    │
                    ▼
3. 기등록 사용자 단말 프로파일 DB 대조 및 유사도(Similarity) 산출
    ┌───────────────┴───────────────┐
 [ 유사도 90% 이상 (정상 기기) ]   [ 유사도 90% 미만 (신규/변조 기기) ]
    │                               │
    ▼                               ▼
정상 등록 기기(Known Device) 확정   낯선 기기 플래그 부여 및 변조 탐지
    │                               │
    └───────────────┬───────────────┘
                    │
                    ▼
4. 접속 IP 평판, 접속 국가, 이상 송금액 결합 종합 위험 점수(Risk Score) 산출
                    │
                    ▼
5. 위험 등급에 따른 적응형 인증 정책(RBA) 분기 집행
    ┌───────────────┼────────────────────────┐
 [ 저위험 (Risk < 30) ] [ 중위험 (30 <= Risk < 70) ] [ 고위험 (Risk >= 70) ]
    │                   │                            │
    ▼                   ▼                            ▼
무자각 즉시 승인        FIDO2 / OTP 2차 인증 요구    거래 강제 보류 및 관제 통보
```

- 분기 결과: 지문 유사도와 거래 맥락을 결합하여 정상 사용자는 통과시키고 이상 징후 시 2차 인증이나 차단을 가동함

**동작 원리**

1. 사용자가 웹이나 앱에 접속하는 순간 백그라운드 자바스크립트가 Canvas 2D 텍스트와 WebGL 3D 셰이더를 보이지 않게 렌더링하여 하드웨어 고유 연산 오차를 추출한다.
2. 수집된 화면 해상도, CPU 코어 수, 타임존 등 50여 개 파라미터를 FDS 서버로 전송하여 가중치 퍼지 해시 알고리즘으로 정규화한다.
3. 서버는 과거 사용자가 로그인했던 디바이스 프로파일 DB와 현재 지문을 비교하여 유사도가 90% 이상인지 판별한다.
4. 디바이스 일치 여부에 접속 IP의 VPN/프록시 여부, 해외 접속 이력, 거래 금액을 결합하여 0~100점의 복합 위험 점수(Risk Score)를 실시간 계산한다.
5. 산출된 위험 점수에 따라 저위험 거래는 마찰 없는 즉시 승인을 내리고, 중·고위험 이상 거래에는 FIDO 생체 인증이나 거래 일시 정지 조치를 차등 집행한다.

#### 한줄 요약
- 지문 일치만으로 판정하면 정상 사용자의 환경 변경까지 막게 되므로, 거래 맥락을 더한 위험 점수로 인증 강도를 차등화해 차단 정확도와 사용자 마찰을 맞바꾼다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **FIDO2(Fast Identity Online 2)**: 비대칭 공개키 암호와 단말 내부 하드웨어 보안 칩을 결합한 생체 인식 기반의 글로벌 패스워드리스 인증 표준.

</details>

| 단말 식별 및 인증 기술 | Device DNA (소프트웨어 핑거프린트) | PUF (하드웨어 반도체 지문) | 정적 하드웨어 식별자 (MAC / IMEI) | FIDO2 (생체 기반 공개키 인증) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 무설치 웹 환경에서 쿠키 없이 금융 FDS 및 이상 거래 탐지 시 | 물리적 실리콘 칩 복제 방지 및 제로 스토리지 하드웨어 보안 구축 시 | 폐쇄형 내부 네트워크의 고정 단말 장비 관리 및 접근 통제 시 | 생체 정보 기반 강력한 사용자 본인 인증 및 패스워드리스 로그인 시 |
| 식별 대상 및 계층 | 웹 브라우저 및 단말 환경 복합체 | 물리 실리콘 반도체 칩셋 | 네트워크 카드 및 통신 모뎀 | 단말 보안 칩(TPM/TEE) 내부 개인키 |
| 사용자 개입 여부 | 완전 무설치 (백그라운드 스크립트) | 하드웨어 칩 설계 시 내장 | OS 권한 획득 필요 | 생체 인식 터치 등 사용자 개입 필수 |
| 식별 특성 | 확률적 식별 (유사도 매칭) | 결정론적 고유성 (100% 식별) | 결정론적 식별 (스푸핑 취약) | 암호학적 인증 (본인 확인) |
| 주요 적용 분야 | 전자금융 **FDS**, 웹 이상 거래 탐지 | IoT 기기 복제 방지, 하드웨어 RoT | 폐쇄망 네트워크 장비 인증 | 패스워드리스 로그인, 비대면 본인인증 |

#### 한줄 요약
- 무설치 이상 거래 탐지에는 Device DNA가, 물리 반도체 복제 방지에는 PUF가, 패스워드리스 사용자 인증에는 **FIDO2**가 사용된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핑거프린트 드리프트(Fingerprint Drift)**: 브라우저 자동 업데이트나 그래픽 드라이버 패치로 인해 정상 기기의 식별 파라미터가 시간이 지남에 따라 서서히 바뀌는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 브라우저 자동 업데이트로 인한 **핑거프린트 드리프트** 발생 | 가중치 기반 **퍼지 매칭** 및 점진적 프로파일 자동 갱신 | 정상 사용자 오차단 방지 및 편의성 유지 |
| 안티디텍트 브라우저를 통한 지문 위조/변조 | HTTP 헤더와 JS 수집값 간 불일치 **교차 검증** 및 행동 패턴 결합 | 사기 도구 및 자동화 스크립트 탐지율 95% 달성 |
| 과도한 단말 정보 수집에 따른 프라이버시 규제 | 비식별 단방향 **솔트 해시** 암호화 및 원본 파라미터 미보존 | 개인정보보호법 및 글로벌 컴플라이언스 준수 |

#### 한줄 요약
- 실무에서는 퍼지 매칭으로 드리프트를 완충하고, 교차 검증으로 지문 위조를 차단하며, 단방향 해시로 프라이버시 규제를 준수한다.

## Ⅶ. 결론

- 사용자 개입 없는 무설치 웹 환경에서 FDS 및 위험 기반 인증(RBA)의 핵심 식별 기술로 자리잡았으며, 향후 안티디텍트 브라우저의 지문 변조 공격에 대응하여 Canvas/WebGL 딥 프로파일링과 AI 기반 사용자 행동 바이오메트릭스(터치 압력, 마우스 궤적)를 결합한 복합 무자각 인증으로 진화하고 있으므로 보안 엔지니어는 핑거프린트 드리프트 완충 로직과 프라이버시 비식별 해시 처리를 동시 설계해야 한다.

#### 한줄 요약
- 디바이스 DNA는 사용자 경험을 해치지 않으면서 이상 거래를 실시간 차단하는 지능형 사기 탐지(FDS)의 핵심 수단이다.
