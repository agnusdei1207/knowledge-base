## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 코어 내부에 집적되어 가상 주소를 물리 주소로 실시간 변환하고, 메모리 접근 권한 및 캐시 정책 등 속성 검사를 하드웨어로 강제하는 핵심 장치.
- **가상 주소(Virtual Address)**: 프로세스가 컴파일 및 실행 시 참조하는 논리 주소로, 물리적 메모리 배치와 완전히 독립적인 주소.
- **물리 주소(Physical Address)**: 메인 메모리(DRAM) 또는 메모리 맵 입출력(MMIO) 하드웨어에 직접 연결되는 실제 시스템 버스 상의 주소.

</details>

- 정의/개념: CPU 코어가 요청한 **가상 주소(VA)**를 **물리 주소(PA)**로 실시간 변환하고 메모리 보호 권한(R/W/X) 및 캐시 속성을 하드웨어로 검증하는 **메모리 관리 장치(MMU)**
- 배경/필요성: 소프트웨어 에뮬레이션 방식의 주소 변환으로는 **극심한 성능 저하 및 하드웨어 강제 권한 격리 불가**

#### 한줄 요약
- MMU는 CPU 내부에서 가상 주소를 물리 주소로 변환하고 메모리 접근 권한을 하드웨어로 강제하는 핵심 장치이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **변환 참조 버퍼(Translation Lookaside Buffer, TLB)**: MMU 내부에 탑재되어 최근 사용된 가상-물리 주소 변환 엔트리를 1클록 내에 제공하는 초고속 캐시(CAM + SRAM).
- **페이지 권한(Page Permissions)**: 각 페이지에 부여된 읽기(R), 쓰기(Write), 실행(Execute), 유저/슈퍼바이저(U/S) 등의 접근 통제 비트.
- **메모리 속성(Memory Attributes)**: 해당 메모리 영역의 캐시 정책(Write-Back/Write-Through/Uncacheable), 쓰기 결합(Write-Combining), 장치 메모리(Device MMIO) 등을 정의하는 하드웨어 제어 비트.

</details>

- 고속 하드웨어 변환: **TLB**를 통해 1클록 내에 주소 변환을 완료하여 메모리 접근 지연시간 최소화
- 강력한 메모리 보호: 하드웨어 비교기를 통해 **페이지 권한(R/W/X, U/S)** 위반을 즉시 탐지하여 프로세스 간 침범 차단
- 세부 메모리 속성 제어: **메모리 속성(Memory Attributes)**을 기반으로 캐시 정책, 버퍼링, 디바이스 메모리 접근 순서를 페이지 단위로 정밀 통제

#### 한줄 요약
- MMU는 TLB를 통한 고속 주소 변환과 권한/속성 하드웨어 검사를 단일 경로에서 원자적으로 처리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 정지하고 DRAM 상의 다단계 페이지 테이블을 계층적으로 순회하여 변환 엔트리를 가져오는 하드웨어 엔진.
- **권한 및 속성 검사기(Access & Attribute Checker)**: CPU의 현재 특권 모드 및 접근 유형과 PTE의 권한/속성 비트를 대조하는 비교 논리 회로.
- **예외 제어기(Exception Controller)**: 주소 변환 실패(Page Fault)나 권한 위반(Protection Fault) 시 CPU에 동기적 트랩을 전달하는 제어기.

</details>

```text
[CPU 코어] ── 가상 주소 (VA: VPN + Offset)
                 │
                 ▼
[메모리 관리 장치 (MMU)]
 ├─ [변환 참조 버퍼 (TLB)] ────── CAM 병렬 검색 ──► 1클록 PPN 출력 (적중 시)
 │
 ├─ [페이지 테이블 워커] ──────── (TLB 미스 시) DRAM 다단계 페이지 테이블 하드웨어 순회
 │                                   └─ PTE 인출 ➔ TLB 리필
 │
 ├─ [권한 및 속성 검사기] ─────── R/W/X, U/S, NX, 캐시 속성(WT/WB/UC) 대조
 │
 └─ [예외 제어기] ─────────────── 위반 시 Page Fault / Protection Fault 인터럽트 발생
                 │ (변환 성공 및 권한 통과 시)
                 ▼
[물리 주소 (PA: PPN + Offset)] ──► [L1/L2/L3 캐시 및 메인 메모리 (DRAM)]
```

선의 의미: 가지(`├─`, `└─`)는 MMU 내부 서브시스템의 소유 및 구성 관계; MMU는 변환과 검사를 거쳐 최종 물리 주소를 캐시/메모리로 출력함

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **TLB** | MMU 내부 고속 캐시 | 최근 사용된 VPN-PPN 매핑 정보를 1클록 내 제공 | CAM 회로 기반 전연관 검색 |
| **페이지 테이블 워커** | MMU 내부 하드웨어 유닛 | TLB 미스 시 DRAM 상의 **다단계 페이지 테이블을 계층 순회** | 하드웨어 기반 자동 리필 |
| **권한/속성 검사기** | MMU 내부 논리 회로 | 현재 실행 모드와 PTE의 **페이지 권한(R/W/X, NX)** 및 속성 검증 | 위반 시 즉시 예외 신호 발생 |
| **예외 제어기** | MMU-코어 인터페이스 | 페이지 부재나 권한 위반 시 CPU에 트랩 예외 통지 | OS 페이지 폴트 핸들러 호출 |

#### 한줄 요약
- MMU는 TLB, 하드웨어 페이지 테이블 워커, 권한/속성 검사기, 예외 제어기가 결합된 하드웨어 유닛이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **실행 방지 비트(No-Execute, NX / XD)**: 스택이나 힙 같은 데이터 영역에서 기계어 명령어가 실행되는 것을 하드웨어적으로 원천 차단하는 보안 비트.
- **페이지 테이블 엔트리(Page Table Entry, PTE)**: 물리 프레임 번호(PPN)와 Present, Dirty, Accessed, R/W, U/S, NX 등 모든 상태 제어 비트를 포함하는 최소 매핑 단위.

</details>

```text
1. CPU 코어의 가상 주소(VA) 메모리 참조 요청
                      │
                      ▼
2. MMU 내부 TLB (CAM) 조회
   ┌──────────────────┴──────────────────┐
[ TLB 적중 (TLB Hit) ]                [ TLB 미스 (TLB Miss) ]
   │                                     │
   │                                     ▼
   │                             3. 페이지 테이블 워커가 DRAM 다단계 페이지 테이블 순회
   │                                     ├─ PTE 발견 ➔ TLB에 엔트리 리필
   │                                     └─ Present=0 ➔ 페이지 폴트(Page Fault) 트랩 발생
   └──────────────────┬──────────────────┘
                      │
                      ▼
4. PTE의 접근 권한(R/W/X, U/S, NX) 및 메모리 속성 하드웨어 검증
   ┌──────────────────┴──────────────────┐
[ 권한 위반 (Access Violation) ]      [ 권한 검증 통과 (Valid) ]
   │                                     │
   ▼                                     ▼
보호 예외(#GP / Segfault) 발생        5. 물리 주소(PA) 생성 ➔ 캐시 및 DRAM 메모리 버스 접근
```

분기 결과: **정상 접근은** TLB 적중을 통해 1클록 내에 물리 주소를 출력하나, **PTE 부재나 권한 위반은** 하드웨어 예외를 발생시켜 OS로 제어를 전환함

#### 한줄 요약
- TLB를 조회하여 적중 시 즉시 검사하고, 미스 시 하드웨어 워커가 페이지 테이블을 순회한 후 권한을 검증하여 물리 주소를 생성한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MPU(Memory Protection Unit)**: 가상 주소 변환 없이 고정 물리 메모리 영역의 접근 권한(R/W/X)만을 검사하는 소형 임베디드용 유닛.

</details>

| 비교 항목 | MMU (Memory Management Unit) | MPU (Memory Protection Unit) |
|:---|:---|:---|
| 핵심 기능 | **가상 주소 ➔ 물리 주소 실시간 변환 + 메모리 보호** | **물리 주소 직접 사용 + 영역별 권한(R/W/X) 보호만 수행** |
| 주소 공간 | 프로세스별 독립된 연속 가상 주소 공간 제공 | 모든 태스크가 단일 물리 주소 공간 공유 |
| 하드웨어 복잡도 | 높음 (TLB, 다단계 페이지 테이블 워커, CAM 회로 필수) | **매우 낮음 (소수의 영역 베이스/리밋 레지스터만 사용)** |
| 실시간 결정성 | 비결정론적 (TLB 미스 및 페이지 워크 지연 발생) | **완벽한 결정론적(Deterministic) 초저지연 응답 보장** |
| 주요 적용처 | **스마트폰, PC, 서버 (Linux, Windows, Android)** | **차량용 제어기, 센서 MCU, 실시간 제어 (RTOS)** |

#### 한줄 요약
- 범용 OS와 대규모 가상 메모리에는 MMU가 필수적이며, 엄격한 실시간 결정성이 요구되는 소형 임베디드에는 MPU가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLB 슛다운(TLB Shootdown)**: 멀티코어 환경에서 한 코어가 페이지 매핑을 변경했을 때, IPI(인터럽트)를 통해 타 코어들의 해당 TLB 엔트리를 강제 무효화하는 동기화 기법.
- **중첩 페이징(Nested Paging / EPT)**: 가상화 환경에서 게스트 가상 주소를 호스트 물리 주소로 2단계 변환하는 하드웨어 지원 페이징 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다단계(4~5단계) 페이지 워크로 인한 메모리 접근 지연 급증 | **대형 페이지(Huge Page: 2MB/1GB)** 및 페이지 워크 캐시 적용 | 계층 순회 단계 단축 및 주소 변환 지연 70% 절감 |
| 멀티코어 환경에서 페이지 테이블 수정 시 **TLB 슛다운** 오버헤드 | **ASID 태그 기반 선택적 무효화** 및 배치 IPI 전송 | 코어 간 인터럽트 동기화 지연 극소화 |
| 가상화 환경(VM)에서 2단계 중첩 변환으로 인한 오버헤드 | **하드웨어 지원 중첩 페이징(Intel EPT, AMD NPT)** 채택 | 가상화 주소 변환 성능을 네이티브의 90% 이상으로 개선 |

#### 한줄 요약
- 실무에서는 대형 페이지를 통한 워크 지연 단축, ASID를 통한 TLB 슛다운 최소화, 하드웨어 EPT를 통한 가상화 가속을 적용한다.

## Ⅶ. 결론

- 범용 컴퓨팅 및 가상 메모리 기반 멀티태스킹 OS 환경을 구축하기 위해 **TLB와 하드웨어 페이지 테이블 워커를 내장한 MMU를 표준 하드웨어 장치로 채택**하고, 결정론적 실시간 제어가 필수적인 환경에는 **MPU를 분리 적용**하며, 가상화 및 고성능 서버 환경에서는 **대형 페이지와 EPT 중첩 페이징 기술**을 융합하는 고성능 메모리 관리 아키텍처 확립

#### 한줄 요약
- MMU는 가상 메모리와 시스템 보안의 하드웨어 핵심이며, 대형 페이지와 가상화 가속 기술을 통해 엔터프라이즈 성능을 보장한다.
