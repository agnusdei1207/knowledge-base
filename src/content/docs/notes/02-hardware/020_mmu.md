## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU와 메모리 버스 사이에 위치하여 가상 주소 변환, 메모리 보호, 캐시 속성을 하드웨어적으로 통제하는 핵심 모듈.
- **접근 격리(Access Isolation)**: 프로세스가 타 프로세스나 커널의 메모리 영역을 무단 침범하지 못하도록 차단하는 하드웨어 보안 체계.
- **하드웨어 보호 경계(Hardware Protection Boundary)**: 소프트웨어적으로 우회가 불가능하도록 모든 메모리 트랜잭션을 실시간 검사하는 물리적 게이트.

</details>

- 정의/개념: CPU와 메모리 버스 사이에 위치하여 가상 주소를 물리 주소로 실시간 변환하고, 메모리 접근 권한 검사 및 캐시 속성을 하드웨어적으로 통제하는 핵심 제어 유닛
- 배경/필요성: 소프트웨어 검사만으로는 불가능한 **우회 불가능한 프로세스 간 메모리 격리, 권한 보호 및 가상 메모리 페이징 가속**

#### 한줄 요약

- 가상-물리 주소 변환과 **하드웨어 메모리 보호 및 캐시 속성 제어**를 총괄하는 핵심 유닛

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **페이지 권한(Page Permissions)**: User/Supervisor 모드 접근 허용 및 Read, Write, Execute(NX/XD 비트) 제어 플래그.
- **캐시 속성(Memory Attributes)**: 메모리 영역별로 Write-Back, Write-Through, Uncacheable, Device Memory 속성을 지정하는 기능.

</details>

- **가상 주소**를 **물리 프레임**으로 실시간 변환하여 비연속 물리 메모리 적재 실현
- 메모리 접근 트랜잭션마다 User/Supervisor 권한 및 **R/W/X 권한** 하드웨어 실시간 검사
- 내부 **변환 색인 버퍼(TLB)** 적중 시 1클록 내 변환 완료를 통한 주소 변환 지연 극소화

#### 한줄 요약

- **동적 주소 변환·TLB 가속·하드웨어 권한 검사**를 단일 파이프라인에서 수행

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 순회기(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 멈추지 않고 메모리의 다단계 페이지 테이블을 자동 탐색하는 하드웨어 엔진.

</details>

```text
[ MMU 내부 아키텍처 및 주소 변환 경로 ]
+---------------------------------------------------+
| CPU 가상 주소 입력 (VPN + Offset)                 |
+---------------------------------------------------+
                          │
                          ▼
            [ 변환 색인 버퍼 (TLB) 조회 ]
            ├─ [Hit] ──> 물리 페이지 번호 (PPN) 즉시 인출
            │
            └─ [Miss] ─> [ 하드웨어 Page Table Walker 가동 ]
                                  │
                                  ▼
                    [ 권한 및 캐시 속성 검사기 ]
                                  │
                    ┌─────────────┴─────────────┐
                    ▼ [위반 시]                 ▼ [통과 시]
          [ Page Fault 트랩 발생 ]    [ 물리 주소 (PPN + Offset) 출력 ]
```

선의 의미: 가상 주소 입력부터 TLB 조회, 페이지 테이블 워커 순회, 권한 검사 및 물리 주소 출력으로 이어지는 MMU 내부 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 변환 색인 버퍼 (TLB) | 최근 주소 변환 매핑 결과와 권한 비트 고속 보관 |
| 페이지 테이블 순회기 | 버퍼 미스 시 메모리의 다단계 페이지 테이블 탐색 수행 |
| 권한 및 속성 검사기 | 읽기/쓰기/실행 보호 권한과 메모리 캐시 속성 대조 |
| 예외 제어기 | 무효 매핑이나 권한 위반에 대한 즉각적인 예외 신호 생성 |

#### 한줄 요약

- **TLB(고속 캐시)·Page Table Walker(하드웨어 순회)·권한 검사기**의 유기적 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NX(No-Execute) / XD 비트**: 데이터 영역(스택/힙)에서 코드가 실행되는 것을 하드웨어적으로 원천 차단하여 버퍼 오버플로 공격을 방어하는 보안 비트.

</details>

```text
[ CPU 가상 주소 접근 요청 ]
            │
            ▼
     [ 1. TLB 조회 및 테이블 탐색 ]
     ├─ 적중 시 ──> PPN 및 권한 비트 즉시 획득
     └─ 미스 시 ──> Page Table Walker 순회 및 TLB 리필 (미상주 시 Page Fault)
            │
            ▼
     [ 2. 권한 및 메모리 속성 검사 ]
     ├─ 권한 위반 (NX 실행 시도, User 영역 커널 침범) ──> Access Exception 발생
     └─ 정상 권한 확인 ──────────────────────────────────> 통과
            │
            ▼
     [ 3. PPN + Offset 결합하여 물리 주소 버스 출력 ]
```

**동작 원리**

1. **주소 탐색**: VPN으로 TLB를 검색하고, 미스 시 하드웨어 워커가 다단계 테이블을 순회하여 PPN 인출
2. **권한 검증**: 현재 CPU 모드(CPL)와 PTE의 U/S, R/W, NX 비트를 대조하여 접근 적합성 검사
3. **물리 주소 출력**: 모든 검증 통과 시 PPN과 Offset을 결합하여 실제 메모리/캐시 버스로 트랜잭션 전송

#### 한줄 요약

- **TLB/PTE 탐색 $\to$ R/W/X 권한 검증 $\to$ 물리 주소(PPN+Offset) 결합 출력**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MMU vs MPU**:
  - MMU: 가상 주소 변환 지원, 가상 메모리 OS 필수, 페이징 지원
  - MPU: 가상 주소 변환 없음(물리 주소 직결), 고정 영역 보호, 실시간 임베디드용

</details>

| 비교 항목 | 메모리 관리 장치 (MMU) | 메모리 보호 장치 (MPU) |
|:---|:---|:---|
| 적용 기준 | 가상 메모리 및 멀티태스킹 OS (Linux, Windows, Android) | 하드 실시간 제어 및 소형 MCU (FreeRTOS, AUTOSAR) |
| 핵심 특징 | 가상 $\to$ 물리 동적 주소 변환, TLB, 요구 페이징 지원 | 주소 변환 없이 고정된 물리 메모리 영역(Region) 권한 검사만 수행 |
| 한계 및 위험 | 페이지 순회로 인한 접근 지연 변동(Non-deterministic) | 가상 주소 공간 확장 불가, 물리 메모리 크기 제약 |

#### 한줄 요약

- MMU는 **가상 주소 변환과 페이징**, MPU는 **물리 영역 보호와 결정론적 실시간성**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **중첩 가상화 페이징(EPT/NPT)**: 가상머신 환경에서 게스트 물리 주소를 호스트 물리 주소로 2단계 변환하는 하드웨어 MMU 확장.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다단계 테이블 순회로 인한 극심한 주소 변환 지연 병목 | 대형 페이지 적용 및 내부 **페이지 순회 캐시** 활성화 | 메모리 순회 빈도 감소 및 최종 접근 지연시간 단축 |
| 다중 코어 간 매핑 수정 시 발생하는 **TLB 슛다운** 통신 폭증 | 무효화 전파 범위를 최소화하는 커널 국지적 동기화 적용 | 코어 간 통신 지연 감소 및 인터럽트 오버헤드 삭감 |
| 하이퍼바이저 가상화 환경에서의 **중첩 페이징** 변환 지연 | 결합형 캐시 버퍼 탑재 및 호스트 중첩 대형 페이지 활용 | 순회 빈도 억제 및 2단계 이중 변환 지연 시간 은닉 |
| 초저지연 실시간 제어에서 폴트에 의한 응답 예측성 파괴 | 운영체제 차원의 **메모리 고정** 연동 및 전용 보호 장치 전환 | 물리적 지연 요인 배제 및 접근 지연의 완벽한 확정성 보장 |

#### 한줄 요약

- **Huge Page·TLB 슛다운 국지화·중첩 페이징(EPT)·Memory Pinning**으로 지연 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **IOMMU**: CPU뿐만 아니라 PCIe/DMA 주변 장치에도 가상 주소 변환과 메모리 격리를 제공하는 장치 전용 MMU.

</details>

- 범용 가상화 OS는 **MMU + TLB 가속**, 확정적 응답이 필수인 실시간 임베디드는 **MPU 채택**

#### 한줄 요약

- **가상화 유연성(MMU)**과 **실시간 결정론적 제어(MPU)**의 시스템 요구별 최적 선택
