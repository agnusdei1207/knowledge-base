## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU와 메인 메모리 버스 사이에 위치하여 가상 주소(VA)를 물리 주소(PA)로 변환하고, 메모리 접근 권한(Read/Write/Execute) 검사 및 캐시 속성을 하드웨어적으로 강제 제어하는 프로세서 내장 제어 모듈.
- **접근 격리(Access Isolation)**: 하드웨어적 주소 변환 경계를 구축하여 특정 프로세스가 타 프로세스나 OS 커널의 물리 메모리 구역을 인가 없이 참조/파괴하지 못하도록 차단하는 보안 성질.
- **하드웨어 보호 경계(Hardware Protection Boundary)**: 소프트웨어적 바이패스가 불가능하도록 CPU 파이프라인 출구 직후에 위치하여 모든 메모리 억세스 트랜잭션을 실시간 필터링하는 물리적 하드웨어 게이트.

</details>

- 정의/개념: CPU가 출력하는 가상 주소를 물리 주소로 동적 변환하고, **하드웨어 보호 경계** 상에서 권한 검사 및 캐시 속성(Cacheable/Non-cacheable)을 통제하는 하드웨어 블록인 **메모리 관리 장치**.
- 배경/필요성: 소프트웨어 검사만으로는 모든 메모리 접근의 주소 격리와 권한을 우회 불가능하게 강제하기 어려움.

#### 한줄 요약
- 모든 메모리 트랜잭션을 하드웨어 레벨에서 가상 주소 물리 주소 변환 및 R/W/X 권한 검사를 수행하는 핵심 제어 모듈.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 주소(Virtual Address, VA)**: 프로세스가 0번지부터 독립적으로 바라보는 논리적 주소 공간.
- **물리 주소(Physical Address, PA)**: 실제 DRAM 메인 메모리 칩에 할당된 핀 버스 하드웨어 억세스 주소.
- **페이지 권한(Page Permission)**: PTE 서술자에 기록된 User/Supervisor 모드 접근 허용 및 Read, Write, Execute-Never(XN) 보호 비트.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: MMU 내부에 탑재되어 최근의 VA->PA 매핑 결과를 1주기 이내로 출력하는 전용 룩업 캐시.
- **물리 프레임(Physical Frame / PFN)**: 물리 메모리 상의 4KB 분할 단위 프레임 번호.

</details>

- **가상 주소**를 **물리 프레임**으로 변환하여 소프트웨어 코드의 비연속 물리 메모리 적재 실현.
- CPU 파이프라인 메모리 억세스 시 매 접근마다 User/Kernel 권한 및 **페이지 권한**을 실시간 하드웨어 검사.
- 내부 **TLB**가 적중하면 다단계 페이지 테이블 탐색을 생략하여 변환 지연 단축.

#### 한줄 요약
- VA->PA 동적 주소 변환, TLB Caching 기반 가속, 실시간 R/W/X 권한 하드웨어 검사 기능을 제공함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 순회기(Page Table Walker)**: TLB 미스(Miss) 발생 시 하드웨어 파이프라인을 멈추고 DRAM 상의 다단계(L1~L4) 페이지 테이블 엔트리를 자동 억세스 탐색하는 로직.

</details>

```text
[ MMU Hardware Internal Architecture ]
┌───────────────────────────────────────────────────────────┐
│ CPU Virtual Address Input (VPN + Offset, Access Type)     │
├───────────────────────────────────────────────────────────┤
│ TLB (Translation Lookaside Buffer)                        │
│  ├─ Hit : PPN + Offset | Permission Checker               │
│  └─ Miss: Hardware Page Table Walker                      │
├───────────────────────────────────────────────────────────┤
│ Permission & Attribute Checker                            │
│  - User/Kernel Level Check, R/W/X Permission Check        │
│  - Memory Attribute (Cacheable / Non-cacheable / Share)   │
├───────────────────────────────────────────────────────────┤
│ Exception Controller : Page Fault / Protection Fault      │
│ Physical Address Output (PA Bus) to Cache & DRAM         │
└───────────────────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| TLB | 최근 **주소 변환•권한 비트** 캐싱 |
| 페이지 테이블 순회기 | 미스 시 **다단계 PTE 탐색** 수행 |
| 권한•속성 검사기 | **R/W/X•메모리 속성** 검사 |
| 예외 제어기 | 무효 매핑•권한 위반의 **예외 신호** 생성 |

#### 한줄 요약
- TLB, Page Table Walker, Permission & Attribute Checker 및 Exception Controller로 통합 구동됨.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가상 페이지 번호(Virtual Page Number, VPN)**: MMU가 TLB 및 페이지 테이블 인덱싱에 사용하는 가상 주소 상위 필드.
- **페이지 오프셋(Page Offset)**: 변환 없이 물리 주소 하위로 복사되는 페이지 내부 바이트 위치.
- **페이지 폴트(Page Fault)**: 비상주 페이지 접근이나 권한 위반 시 MMU가 발생시켜 CPU 제어를 OS로 넘기는 예외 트랩.

</details>

```text
[ CPU Virtual Address (VPN + Offset) Access Request ]
                         │
                         ▼
             [ 1. TLB•Page Walk 탐색 ]
             ├─ [ Hit ]  ──> PPN & Permission Info 인출
             └─ [ Miss ] ──> Page Table Walker 가동
                                   ├─ Valid PTE : TLB Refill & PPN 인출
                                   └─ Invalid   : [ Page Fault Trap -> OS ]
                         │
                         ▼
             [ 2. 권한•속성 검사 ]
             ├─ Violation (권한 위반) ──> [ Protection Fault Trap ]
             └─ Valid (정상 접근)
                         │
                         ▼
             [ 3. 물리 주소 확정 ]
```

### 동작 원리

1. **TLB•Page Walk 탐색**: **VPN** 조회 후 미스면 PTE에서 PPN•권한을 인출함.
2. **권한•속성 검사**: 실행 모드•접근 종류와 PTE 권한을 대조함.
3. **물리 주소 확정**: **PPN•Offset** 결합 후 속성과 함께 메모리 계층에 전달함.

#### 한줄 요약
- TLB/Page Walk 탐색 -> Permission Check -> PA 생성 및 Attribute 출력 순서로 변환과 검사를 진행함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **메모리 보호 장치(Memory Protection Unit, MPU)**: 주소 변환(VA->PA) 기능 없이, 물리 주소 공간의 몇 개 고정 영역(Region)에 대해서만 접근 권한을 검사하는 저가형 하드웨어 블록.
- **실시간 예측성(Real-Time Predictability)**: 주소 변환이나 TLB 미스 지연 변동 없이 확정된 시간(Deterministic Latency) 내에 메모리 억세스를 완료하는 성질.
- **요구 페이징(Demand Paging)**: 가상 메모리를 통해 참조 시점에만 페이지를 물리 RAM에 동적 로드하는 기법.

</details>

| 비교 항목 | 메모리 관리 장치 (MMU) | 메모리 보호 장치 (MPU) |
|:---|:---|:---|
| **주소 변환 (VA->PA)** | **지원함** (가상 메모리 및 요구 페이징 지원) | **미지원** (Logical Address = Physical Address) |
| **보호 제어 단위** | 페이지 크기별 세밀한 매핑•권한 제어 | 구현별 제한된 물리 영역 단위 제어 |
| **지연 확정성** | TLB Miss 시 Page Walk로 **지연 변동 발생** | 주소 변환이 없어 **실시간 예측성** 보장 |
| **하드웨어 칩 면적**| 크고 복잡함 (TLB, Page Walker, CAM 필요) | 매우 작고 단순함 (구간 비교기만 탑재) |
| **주요 채택 분야** | 범용 OS (Linux, Android, Windows), 고성능 AP | 하드 실시간 RTOS, 자동차 MCU (AUTOSAR), Cortex-M |

#### 한줄 요약
- MMU는 가상 주소 변환 및 동적 요구 페이징을 지원하며, MPU는 주소 변환 없이 고정 영역 보호 및 실시간 억세스 확정성을 제공함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLB 슛다운(TLB Shootdown)**: 멀티코어 환경에서 한 코어가 페이지 테이블을 수정했을 때, 타 코어들의 TLB 내 구버전 엔트리를 무효화하기 위해 Inter-Processor Interrupt(IPI)를 발생시키는 작업.
- **중첩 페이징(Nested Paging / Extended Page Table, EPT)**: 하이퍼바이저 가상화 환경에서 게스트 가상 주소(GVA) -> 게스트 물리 주소(GPA) -> 호스트 물리 주소(HPA)로 2단계 MMU 변환을 수행하는 하드웨어 가상화 기술.
- **메모리 고정(Memory Pinning / Locking)**: 실시간 레이턴시가 중요한 페이지를 물리 메모리에 강제로 상주(Lock)시켜 MMU Page Fault 지연을 물리 차단하는 기법.

</details>

| 문제 및 병목 원인 | 실무적 대책 및 해결 방안 | 기대 효과 |
|:---|:---|:---|
| 다단계 페이지 순회로 주소 변환 지연 | **Huge Page** 적용 및 **MMU Page Walk Cache** 활성화 | 순회 빈도와 실제 PTE 메모리 접근 감소 |
| 멀티코어 간 페이지 테이블 수정 시 **TLB 슛다운(Shootdown)** 트래픽 발생 | IPI 전파 범위를 최소화하는 커널 **Range Invalidation** 적용 | 코어 간 슛다운 동기화 지연시간 대폭 감소 |
| 하이퍼바이저에서 **중첩 페이징** 변환 오버헤드 | **결합 TLB** 및 중첩 Huge Page 활용 | 페이지 순회 빈도와 가상화 변환 지연 감소 |
| RTOS 및 초저지연 제어계통에서 MMU Page Fault에 의한 미스 지연 | **메모리 고정** 연동 및 MPU 전환 | 억세스 레이턴시 확정성(Deterministic Latency) 보장 |

#### 한줄 요약
- Huge Page 적용, Range TLB Shootdown 최적화, Hardware EPT 내장 및 Memory Pinning 체계를 도입함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **MMU 설계 판단 기준(MMU Architecture Decision Criteria)**: 대상 시스템의 운영체제 종류(범용 Linux vs 실시간 RTOS), 가상화 요구, 지연 확정성(Deterministic Latency)을 정밀 평가하여 MMU/MPU 채택을 결정하는 프레임워크.

</details>

- 가상 메모리•가상화가 필요하면 **MMU**, 확정 지연•영역 보호면 **MPU** 선택.

#### 한줄 요약
- 주소 변환 요구와 지연 확정성을 기준으로 MMU•MPU를 결정함.
