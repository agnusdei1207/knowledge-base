## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: 가상 주소를 물리 주소로 변환하고 접근 권한을 하드웨어로 검사하는 장치.
- **가상 주소(Virtual Address)**: 프로세스가 사용하는 논리 주소 공간의 주소; 물리 주소와 독립.
- **물리 주소(Physical Address)**: 실제 메모리 장치에서 데이터 위치를 지정하는 주소.

</details>

- 정의/개념: CPU의 논리 가상 주소를 물리 주소로 실시간 변환하고 **메모리 접근 권한을 검사**하는 핵심 하드웨어 유닛
- 배경/필요성: 다중 프로세스 환경에서 소프트웨어 주소 변환의 성능 지연 해소 및 프로세스 간 무단 메모리 침범 방지 필요

#### 한줄 요약
- MMU는 프로그램의 주소를 실제 메모리 위치로 바꾸고, 그 프로그램이 그 위치를 접근해도 되는지를 함께 확인한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **페이지 권한(Page Permissions)**: 메모리 페이지의 읽기(R)·쓰기(W)·실행(X) 허용 여부를 나타내는 권한 비트.
- **메모리 속성(Memory Attributes)**: 메모리 영역의 캐시 가능 여부·장치 메모리·쓰기 순서 등의 접근 특성 속성.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 가상→물리 변환 결과를 캐싱해 반복 페이지 테이블 순회를 생략하는 캐시.

</details>

- **TLB** 기반 빠른 변환으로 매 메모리 접근마다 페이지 테이블 순회 생략
- R/W/X **페이지 권한** 하드웨어 검사로 프로세스 간 불법 접근 즉시 차단
- **메모리 속성**으로 캐시 가능 여부·장치 메모리 등 접근 특성을 페이지 단위로 제어

#### 한줄 요약
- MMU는 주소를 바꾸는 계산기이면서, 읽기·쓰기·실행 권한과 캐시 속성까지 메모리 접근 순간에 판단하는 보호 경계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 시 다단계 페이지 테이블을 하드웨어로 순회해 가상→물리 매핑을 탐색하는 기능.
- **권한 검사기(Access Checker)**: 현재 실행 모드와 접근 종류를 PTE 권한 비트와 비교하는 회로.
- **예외 제어기(Exception Controller)**: 무효 매핑과 권한 위반을 CPU 예외(페이지 폴트·보호 예외)로 전달하는 제어기.

</details>

```text
[MMU]
├─ TLB  (가상→물리 변환 캐시)
├─ 페이지 테이블 워커  (TLB 미스 시 순회)
├─ 권한·속성 검사기  (R/W/X·메모리 속성)
└─ 예외 제어기  (변환·권한 오류 → CPU 예외)
```

선의 의미: 가지(`├─`)는 소유 관계; 변환 경로는 TLB → TLB 미스 시 워커 → 검사기 → 물리 접근

| 구성요소 | 책임 |
|:---|:---|
| TLB | 최근 가상→물리 매핑 즉시 제공 |
| 페이지 테이블 워커 | **TLB 미스** 시 페이지 테이블 순회·리필 |
| 권한·속성 검사기 | **페이지 권한** R/W/X·**메모리 속성** 검증 |
| 예외 제어기 | 변환·권한 오류를 CPU 예외로 전달 |

#### 한줄 요약
- TLB가 빠른 길을 제공하고 워커가 놓친 매핑을 찾으며, 검사기와 예외 제어기가 안전한 접근만 통과시킨다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **실행 금지(No-Execute, NX)**: 데이터 페이지에 명령어 실행을 금지하는 권한 비트; 코드 주입 공격 방어.
- **페이지 테이블 엔트리(Page Table Entry, PTE)**: 물리 프레임 번호·권한·유효 상태를 담은 매핑 항목.

</details>

```text
CPU 가상 주소 접근
      │
      ▼
1. TLB 조회 및 워커 순회
      │
      ├─ TLB 적중 → 권한 검사 단계 진입
      │
      └─ TLB 미스 → 페이지 테이블 워커 순회 → PTE 확보 → TLB 리필 → 권한 검사
                          │
                          └─ 유효 매핑 없음 → 페이지 폴트 예외
      │
      ▼
2. 권한 및 속성 검사
      │
      ├─ 권한 위반·NX 위반 → 보호 예외 발생
      │
      └─ 통과 → 3. 물리 주소 생성 및 접근 (캐시·메모리 요청)
```

**동작 원리**

1. **TLB 조회 및 워커 순회**: TLB에서 PPN 확보, TLB 미스 시 워커가 PTE 순회
2. **권한 및 속성 검사**: PTE 권한과 접근 종류 비교, NX 비트로 코드 실행 차단
3. **물리 주소 생성 및 접근**: 검사 통과 후 물리 주소로 캐시 및 메모리 요청

#### 한줄 요약
- MMU는 번역을 찾고, 그 번역이 읽기·쓰기·실행 요청에 허용되는지 확인한 뒤 물리 메모리에 접근시킨다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **메모리 보호 장치(Memory Protection Unit, MPU)**: 주소 변환 없이 정해진 물리 영역의 접근 권한을 검사하는 임베디드 전용 장치.

</details>

| 메모리 보호 방식 | MMU | MPU |
|:---|:---|:---|
| 적용 기준 | 가상 메모리·멀티태스킹 OS·프로세스 격리 | 결정적 응답·단순 보호 필요 임베디드 |
| 핵심 특징 | 가상→물리 변환·**페이지 권한** 보호 | 물리 영역 고정 권한 검사·변환 없음 |
| 한계 | 페이지 워크 지연 변동·TLB 슛다운 비용 | 가상 주소 공간·비연속 배치 미지원 |

#### 한줄 요약
- 큰 주소 공간과 프로세스 격리가 필요하면 MMU, 단순하고 결정적인 보호가 필요하면 MPU를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLB 슛다운(TLB Shootdown)**: 한 코어의 매핑 변경을 다른 코어의 TLB에도 알려 오래된 변환 항목을 무효화하는 처리.
- **중첩 페이징(Nested Paging)**: 가상 머신의 주소를 게스트 페이지 테이블과 호스트 페이지 테이블로 두 단계 변환하는 방식.
- **페이지 고정(Memory Pinning)**: 특정 페이지가 교체되지 않도록 물리 메모리에 고정해 폴트를 방지하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다단계 페이지 워크로 변환 지연 증가 | 대형 페이지·페이지 워크 캐시 적용 | 반복 변환·메모리 접근 감소 |
| 매핑 변경마다 **TLB 슛다운** 비용 | 변경 범위 최소화·선택적 무효화 | 코어 간 동기화 지연 감소 |
| **중첩 페이징**으로 가상화 변환 증가 | 중첩 대형 페이지·변환 캐시 활용 | 게스트 주소 변환 비용 완화 |
| 실시간 경로에서 **페이지 폴트** 발생 | **페이지 고정**·사전 접근 적용 | 지연 변동·예외 경로 제거 |

#### 한줄 요약
- MMU 최적화는 변환 캐시를 빠르게 만드는 일뿐 아니라, 매핑 변경·가상화·실시간 페이지 부재까지 줄이는 일이다.

## Ⅶ. 결론

- 가상 메모리와 프로세스 격리는 **MMU**, 결정적 실시간 보호는 **MPU** 선택

#### 한줄 요약
- MMU는 OS의 유연한 메모리 관리에 적합하고, 실시간 시스템은 변환·폴트 비용까지 측정해 보호 방식을 결정해야 한다.
