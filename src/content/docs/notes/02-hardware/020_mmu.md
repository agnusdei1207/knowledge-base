## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU와 메모리 서브시스템 사이에 위치하여 가상 주소를 물리 주소로 실시간 변환하고, 메모리 접근 권한 및 속성 검사를 하드웨어로 강제하는 핵심 제어 장치.
- **가상 주소(Virtual Address)**: 프로세스가 컴파일 및 실행 시 참조하는 논리 주소 공간상의 주소로, 물리적 메모리 배치와 완전히 독립적인 주소.
- **물리 주소(Physical Address)**: 메인 메모리(DRAM) 또는 메모리 맵 입출력(MMIO) 하드웨어에 직접 연결되는 실제 시스템 버스 상의 물리 주소.

</details>

- 정의/개념: **가상 주소**를 **물리 주소**로 실시간 변환하면서 접근 권한까지 같은 경로에서 검사하는 **메모리 관리 장치(MMU)**
- 배경/필요성: 소프트웨어 주소 변환 방식만으로는 **상시 지연 발생 및 하드웨어 강제 격리 불가**

#### 한줄 요약
- 변환과 검사를 한 경로에 합친 것이 MMU의 핵심이며, 덕분에 검사를 건너뛰는 접근 경로 자체가 존재하지 않게 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **페이지 권한(Page Permissions)**: 각 페이지에 설정된 읽기(Read), 쓰기(Write), 실행(Execute) 등의 접근 허용 속성 비트.
- **메모리 속성(Memory Attributes)**: 해당 메모리 영역의 캐시 정책(Write-Back/Write-Through/Uncacheable), 버퍼링 가능 여부, 디바이스 메모리 여부 및 메모리 접근 순서(Strongly-Ordered) 등을 규정하는 하드웨어 제어 속성.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 사용된 가상 주소-물리 주소 변환 결과를 저장하여 다단계 페이지 테이블 순회 지연을 제거하는 초고속 주소 변환 캐시.

</details>

- **TLB** 기반 빠른 변환으로 매 메모리 접근마다 페이지 테이블 순회 생략
- R/W/X **페이지 권한** 하드웨어 검사로 프로세스 간 불법 접근 즉시 차단
- **메모리 속성**을 통해 캐시 가능 여부·장치 메모리 등 접근 특성을 페이지 단위로 제어

#### 한줄 요약
- **메모리 속성**까지 같은 표에 실린 덕분에 캐시 정책이 페이지 단위로 갈리며, 이 때문에 성능 문제와 정합성 문제가 같은 자료구조에서 결정된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 하드웨어가 자동으로 CR3/TTBR 레지스터의 루트 주소부터 시작하여 다단계 페이지 테이블을 순회(Page Walk)하고 변환 엔트리를 인출하는 하드웨어 엔진.
- **권한 검사기(Access Checker)**: CPU의 현재 실행 모드(User/Kernel) 및 메모리 접근 유형(Read/Write/Fetch)을 PTE의 권한 비트(R/W/X, U/S)와 대조하여 적합성을 판정하는 비교 논리 회로.
- **예외 제어기(Exception Controller)**: 주소 변환 실패(Page Fault)나 메모리 접근 권한 위반(Protection Fault) 발생 시 CPU 파이프라인을 중단하고 적절한 예외 인터럽트 벡터를 호출하는 제어기.

</details>

```text
[MMU]
├─ TLB  (가상→물리 변환 캐시)
├─ 페이지 테이블 워커  (TLB 미스 시 순회)
├─ 권한·속성 검사기  (R/W/X·메모리 속성)
└─ 예외 제어기  (변환·권한 오류 → CPU 예외)
```

선의 의미: 가지(`├─`)는 MMU가 소유한 변환 캐시·미스 처리·검사·예외 책임

| 구성요소 | 책임 |
|:---|:---|
| TLB | 최근 가상→물리 매핑 즉시 제공 |
| **페이지 테이블 워커** | TLB에 없는 변환을 페이지 테이블에서 순회·리필 |
| **권한 검사기** | **페이지 권한** R/W/X와 **메모리 속성** 검증 |
| **예외 제어기** | 변환 실패·권한 위반을 CPU 예외로 전달 |

#### 한줄 요약
- 네 구성요소 중 셋은 성능을 위한 것이고 예외 제어기만 정확성을 위한 것이지만, 그 하나가 없으면 나머지 셋의 결과를 신뢰할 수 없다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **실행 금지(No-Execute, NX)**: 데이터 영역(스택, 힙 등)에 악성 코드가 주입되어 실행되는 것을 방지하기 위해 명령어 인출(Instruction Fetch)을 하드웨어적으로 원천 차단하는 보안 비트(AMD XD, ARM XN).
- **페이지 테이블 엔트리(Page Table Entry, PTE)**: 물리 프레임 번호(PPN), Present, Dirty, Accessed, R/W, U/S, NX 등 페이지의 물리 위치와 상태 및 보안 제어 비트를 모두 포함하는 최소 매핑 단위 항목.

</details>

```text
CPU 가상 주소 접근
      │
      ▼
1. TLB 조회 및 미스 처리
      │
      ├─ TLB 적중 → 권한 검사 단계 진입
      │
      └─ TLB 미스 → 페이지 테이블 워커 순회 → PTE 확보 → TLB 리필 → 권한 검사
                          │
                          └─ 유효 매핑 없음 → 페이지 폴트 예외
      │
      ▼
2. 권한 및 속성 검사
      │
      ├─ 권한 위반·NX 위반 → 보호 예외 발생
      │
      └─ 통과 → 3. 물리 주소 생성 및 접근 (캐시·메모리 요청)
```

분기 결과: 변환 실패는 매핑이 없다는 뜻이라 OS가 채워 주면 재개되지만, **NX**를 포함한 권한 위반은 매핑이 있는데도 거부된 것이라 재시도해도 결과가 같음

#### 한줄 요약
- **페이지 테이블 엔트리(Page Table Entry, PTE)** 하나가 위치와 권한을 함께 담기 때문에, 매핑을 고치는 일과 권한을 고치는 일이 같은 갱신 경로를 공유한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MMU(Memory Management Unit)**: 가상 주소 변환과 권한 검사를 동시에 수행하는 고성능 범용 프로세서용 유닛.
- **MPU(Memory Protection Unit)**: 주소 변환 없이 고정 물리 영역의 접근 권한만 검사하는 실시간 임베디드용 유닛.

</details>

| 메모리 보호 방식 | MMU | MPU |
|:---|:---|:---|
| 적용 기준 | 가상 메모리·멀티태스킹 OS·프로세스 격리 | 결정적 응답·단순 보호 필요 임베디드 |
| 핵심 특징 | 가상→물리 변환·**페이지 권한** 보호 | 물리 영역 고정 권한 검사·변환 없음 |
| 한계 | 페이지 워크 지연 변동·TLB 슛다운 비용 | 가상 주소 공간·비연속 배치 미지원 |

#### 한줄 요약
- **MPU가** 선택되는 진짜 이유는 저렴함이 아니라 변환 단계가 없어 접근 시간이 항상 일정하다는 점이며, 실시간 시스템은 평균보다 이 일정함을 산다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLB 슛다운(TLB Shootdown)**: 멀티코어 환경에서 한 코어가 페이지 테이블 매핑을 변경했을 때, 인터프로세서 인터럽트(IPI)를 통해 다른 모든 코어에게 해당 가상 주소의 TLB 엔트리를 강제 무효화하도록 지시하는 동기화 프로토콜.
- **중첩 페이징(Nested Paging)**: 하드웨어 지원 가상화(Intel EPT, AMD NPT) 환경에서 게스트 가상 주소(GVA)를 게스트 물리 주소(GPA)로, 다시 호스트 물리 주소(HPA)로 변환하는 2단계 하드웨어 페이징 기법.
- **페이지 고정(Memory Pinning)**: 실시간 작업이나 DMA 버퍼의 물리 페이지를 메모리에 상주하도록 고정(mlock)하여 페이지 폴트 발생과 스왑 아웃(Swap-Out)을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다단계 페이지 워크로 변환 지연 증가 | 대형 페이지·페이지 워크 캐시 적용 | 반복 변환·메모리 접근 감소 |
| 매핑 변경마다 **TLB 슛다운** 비용 | 변경 범위 최소화·선택적 무효화 | 코어 간 동기화 지연 감소 |
| **중첩 페이징**으로 인한 가상화 변환 부하 증가 | 중첩 대형 페이지·변환 캐시 활용 | 게스트 주소 변환 비용 완화 |
| 실시간 경로에서 페이지 부재 예외 발생 | **페이지 고정** 및 사전 접근으로 상주 강제 | 지연 변동과 예외 경로 제거 |

#### 한줄 요약
- 네 문제 모두 변환 자체가 아니라 변환 상태를 바꾸거나 겹칠 때 생기므로, MMU 비용은 정적인 조회가 아니라 동적인 갱신에서 나온다.

## Ⅶ. 결론

- 범용 가상 메모리는 **MMU**, 실시간 결정성은 **MPU** 선택

#### 한줄 요약
- MMU와 MPU의 선택은 보호 수준의 문제가 아니라 지연의 평균을 살 것인지 최악값을 살 것인지의 문제이며, 두 값은 같은 방향으로 움직이지 않는다.
