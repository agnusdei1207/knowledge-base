## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 코어 내부에 집적되어 가상 주소를 물리 주소로 실시간 변환하고, 메모리 접근 권한 및 캐시 정책 등 속성 검사를 하드웨어로 강제하는 핵심 장치.
- **가상 주소(Virtual Address)**: 프로세스가 컴파일 및 실행 시 참조하는 논리 주소로, 물리적 메모리 배치와 완전히 독립적인 주소.
- **물리 주소(Physical Address)**: 메인 메모리(DRAM) 또는 메모리 맵 입출력(MMIO) 하드웨어에 직접 연결되는 실제 시스템 버스 상의 주소.

</details>

- 정의/개념: CPU 코어가 요청한 **가상 주소**(VA)를 **물리 주소**(PA)로 실시간 변환하고 메모리 보호 권한(R/W/X) 및 속성을 하드웨어로 검증하는 메모리 관리 장치
- 배경/필요성: 소프트웨어 주소 변환은 **접근 지연**과 권한 검사 비용 증가

#### 한줄 요약
- MMU는 CPU 내부에서 가상 주소를 물리 주소로 변환하고 메모리 접근 권한을 하드웨어로 강제하는 핵심 장치이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **변환 참조 버퍼(Translation Lookaside Buffer, TLB)**: MMU 내부에 탑재되어 최근 사용된 가상-물리 주소 변환 엔트리를 1클록 내에 제공하는 초고속 캐시(CAM + SRAM).
- **페이지 권한(Page Permissions)**: 각 페이지에 부여된 읽기(R), 쓰기(Write), 실행(Execute), 유저/슈퍼바이저(U/S) 등의 접근 통제 비트.
- **메모리 속성(Memory Attributes)**: 해당 메모리 영역의 캐시 정책(Write-Back/Write-Through/Uncacheable), 쓰기 결합(Write-Combining), 장치 메모리(Device MMIO) 등을 정의하는 하드웨어 제어 비트.

</details>

- **TLB**(변환 참조 버퍼)를 통한 1클록 내 주소 변환 및 메모리 접근 지연 최소화
- 하드웨어 비교기를 통한 **페이지 권한**(R/W/X, U/S) 검증 및 프로세스 침범 차단
- 페이지별 **메모리 속성**(Memory Attributes) 설정을 통한 캐시 정책 및 MMIO 통제

#### 한줄 요약
- MMU는 TLB를 통한 고속 주소 변환과 권한/속성 하드웨어 검사를 단일 경로에서 원자적으로 처리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 정지하고 DRAM 상의 다단계 페이지 테이블을 계층적으로 순회하여 변환 엔트리를 가져오는 하드웨어 엔진.
- **권한 및 속성 검사기(Access & Attribute Checker)**: CPU의 현재 특권 모드 및 접근 유형과 PTE의 권한/속성 비트를 대조하는 비교 논리 회로.
- **예외 제어기(Exception Controller)**: 주소 변환 실패(Page Fault)나 권한 위반(Protection Fault) 시 CPU에 동기적 트랩을 전달하는 제어기.

</details>

```text
메모리 관리 장치 (MMU)
 ├─ 변환 참조 버퍼 (TLB: CAM + SRAM)
 ├─ 페이지 테이블 워커 (Page Table Walker)
 ├─ 권한 및 속성 검사기 (Access & Attribute Checker)
 └─ 예외 제어기 (Exception Controller)
```

선의 의미: 가지(`├─`, `└─`)는 MMU 내부 하드웨어 모듈의 계층 포함 관계

| 구성요소 | 책임 |
|:---|:---|
| TLB | 최근 **VPN-PPN 매핑**을 1클록 내 제공 |
| 페이지 테이블 워커 | 미스 시 **다단계 페이지 테이블** 순회 |
| 권한 및 속성 검사기 | PTE의 **페이지 권한**과 메모리 속성 검증 |
| 예외 제어기 | 페이지 부재·권한 위반을 트랩으로 통지 |

#### 한줄 요약
- MMU는 TLB, 하드웨어 페이지 테이블 워커, 권한/속성 검사기, 예외 제어기가 결합된 하드웨어 유닛이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **실행 방지 비트(No-Execute, NX / XD)**: 스택이나 힙 같은 데이터 영역에서 기계어 명령어가 실행되는 것을 하드웨어적으로 원천 차단하는 보안 비트.
- **페이지 테이블 엔트리(Page Table Entry, PTE)**: 물리 프레임 번호(PPN)와 Present, Dirty, Accessed, R/W, U/S, NX 등 모든 상태 제어 비트를 포함하는 최소 매핑 단위.

</details>

```text
CPU 코어 가상 주소(VA) 참조 요청
       │
       ▼
1. TLB 병렬 태그 대조
       │
       ├─ 적중 (TLB Hit) ──► 3. PTE 권한·속성 검증
       │
       └─ 미스 (TLB Miss)
              │
              ▼
       2. 다단계 페이지 테이블 순회
              │
              ├─ 부재 (Present=0) ──► 페이지 폴트(Page Fault) 트랩 발생
              │
              └─ 유효 매핑 ──► TLB 엔트리 리필 및 전진
                                      │
                                      ▼
                               3. PTE 권한·속성 검증
                                      │
                                      ├─ 권한 위반 ──► 보호 예외(#GP Fault) 발생
                                      │
                                      └─ 검증 통과 ──► 4. 물리 주소 생성·접근
```

분기 결과: **정상 접근**은 TLB 1클록 내 물리 주소 생성, **PTE 부재나 권한 위반**은 하드웨어 트랩 예외를 통한 OS 제어 전환

**동작 원리**

1. **TLB 병렬 태그 대조**: VPN·ASID로 변환 엔트리 검색
2. **다단계 페이지 테이블 순회**: 유효 매핑을 찾아 TLB 리필
3. **PTE 권한·속성 검증**: 접근 유형과 페이지 속성 대조
4. **물리 주소 생성·접근**: PPN과 오프셋 결합 후 버스 접근

#### 한줄 요약
- TLB를 조회하여 적중 시 즉시 검사하고, 미스 시 하드웨어 워커가 페이지 테이블을 순회한 후 권한을 검증하여 물리 주소를 생성한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MPU(Memory Protection Unit)**: 가상 주소 변환 없이 고정 물리 메모리 영역의 접근 권한(R/W/X)만을 검사하는 소형 임베디드용 유닛.

</details>

| 비교 항목 | MMU (Memory Management Unit) | MPU (Memory Protection Unit) |
|:---|:---|:---|
| 핵심 기능 | **가상-물리 주소 변환** 및 메모리 보호 | 물리 주소 직접 사용 및 **영역별 권한 보호** |
| 주소 공간 | 프로세스별 **독립 가상 주소 공간** 제공 | 태스크 간 **단일 물리 주소 공간** 공유 |
| 하드웨어 복잡도 | 복잡 (TLB, 워커, CAM 회로 필수) | **단순**(베이스/리밋 레지스터 구성) |
| 실시간 결정성 | 비결정론적 (TLB 미스 지연 발생) | **결정론적**(Deterministic) 초저지연 보장 |
| 주요 적용처 | **범용 컴퓨팅**(서버, PC, 스마트폰) | **실시간 제어**(차량 MCU, RTOS) |

#### 한줄 요약
- 범용 OS와 대규모 가상 메모리에는 MMU가 필수적이며, 엄격한 실시간 결정성이 요구되는 소형 임베디드에는 MPU가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLB 슛다운(TLB Shootdown)**: 멀티코어 환경에서 한 코어가 페이지 매핑을 변경했을 때, IPI(인터럽트)를 통해 타 코어들의 해당 TLB 엔트리를 강제 무효화하는 동기화 기법.
- **중첩 페이징(Nested Paging / EPT)**: 가상화 환경에서 게스트 가상 주소를 호스트 물리 주소로 2단계 변환하는 하드웨어 지원 페이징 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 다단계 페이지 워크에 따른 메모리 접근 지연 | **대형 페이지**(Huge Page) 및 페이지 워크 캐시 적용 | 계층 순회 단계 단축 및 변환 지연 70% 절감 |
| 페이지 테이블 수정 시 멀티코어 **TLB 슛다운** 오버헤드 | **ASID 태깅** 기반 선택적 무효화 및 배치 IPI 전송 | 코어 간 인터럽트 동기화 지연 최소화 |
| 가상화 환경(VM) 2단계 중첩 변환에 따른 지연 | **하드웨어 지원 중첩 페이징**(Intel EPT, AMD NPT) 채택 | 가상화 주소 변환 성능을 네이티브 90% 이상으로 개선 |

#### 한줄 요약
- 실무에서는 대형 페이지를 통한 워크 지연 단축, ASID를 통한 TLB 슛다운 최소화, 하드웨어 EPT를 통한 가상화 가속을 적용한다.

## Ⅶ. 결론

- 가상 메모리·가상화는 **MMU**, 결정적 물리 보호는 **MPU** 선택

#### 한줄 요약
- MMU는 가상 메모리와 시스템 보안의 하드웨어 핵심이며, 대형 페이지와 가상화 가속 기술을 통해 엔터프라이즈 성능을 보장한다.
