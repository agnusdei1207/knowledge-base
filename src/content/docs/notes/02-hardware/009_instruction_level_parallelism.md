## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism, ILP)**: 단일 프로그램 스레드 내에서 의존성이 없는 독립 명령어들을 동일 주기에 동시 실행하는 병렬 기법.
- **슈퍼스칼라(Superscalar)**: 단일 클록에 복수의 명령어를 인출, 해독, 실행할 수 있는 다중 실행 파이프라인 구조.
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 프로세서가 단일 클록 주기에 처리 완료하는 평균 명령어 수.

</details>

- 정의/개념: 단일 프로그램 스레드 내에서 상호 독립적인 명령어들을 동시에 인출, 해독, 실행하는 프로세서 하드웨어의 명령어 수준 병렬성(ILP) 기법
- 배경/필요성: 순차 파이프라인의 데이터 의존성 대기 및 하드웨어 유휴를 제거하고 **단일 스레드 실행 속도 및 IPC 극대화**

#### 한줄 요약

- 독립된 명령어들의 동시 다중 발행을 통해 **단일 스레드 처리량(IPC)** 극대화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비순차 실행(Out-of-Order Execution, OoO)**: 데이터 준비가 완료된 명령어부터 순서와 무관하게 먼저 연산하고 결과는 순서대로 확정하는 기술.
- **순차 커밋(In-Order Commit)**: 비순차 실행된 연산 결과를 프로그램 본래의 순서대로 아키텍처 상태(레지스터/메모리)에 반영하는 기법.

</details>

- 다중 디코더와 다중 연산기를 통한 **슈퍼스칼라 동시 다중 발행(Issue Width)** 실현
- **비순차 실행(OoO)**과 **순차 커밋(ROB)** 결합을 통한 정밀 인터럽트 및 실행 일관성 유지
- 데이터 의존성, 분기 오예측, 캐시 미스로 인한 **발행 슬롯 유휴(Slot Waste) 최소화**

#### 한줄 요약

- **슈퍼스칼라와 비순차 실행(OoO)**으로 의존성 없는 명령어 동시 처리

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터 리네이밍(Register Renaming)**: 소수의 아키텍처 레지스터를 다수의 물리 레지스터에 매핑하여 WAR/WAW 가짜 의존성을 제거하는 기술.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차 실행 결과를 임시 보관하여 원래 순서대로 커밋시키는 원형 큐 버퍼.

</details>

```text
[ 슈퍼스칼라 비순차 실행 아키텍처 ]
┌───────────────────────────────────────────────────────────┐
│ 프런트엔드 : 명령어 인출(Fetch) ──> 다중 디코더(Decode)  │
├───────────────────────────────────────────────────────────┤
│ 레지스터 리네이밍 (RAT) : 물리 레지스터 매핑 (WAR/WAW 제거) │
├───────────────────────────────────────────────────────────┤
│ 이슈 큐 / 예약 스테이션 : 연산 준비 완료 시 비순차 발행  │
│  ├─ ALU 1 / ALU 2        ├─ Load/Store Unit               │
│  └─ Vector/FPU Unit      └─ Branch Unit                   │
├───────────────────────────────────────────────────────────┤
│ 재주문 버퍼 (ROB) : 프로그램 원래 순서대로 순차 커밋(Commit)│
└───────────────────────────────────────────────────────────┘
```

선의 의미: 인출·디코딩부터 리네이밍, 비순차 연산기 발행 및 재주문 버퍼(ROB) 순차 커밋으로 이어지는 ILP 하드웨어 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 프런트엔드 | 분기 예측, 다중 인출 및 해독 수행 |
| 레지스터 리네이밍 | 물리 레지스터 매핑으로 **가짜 데이터 의존성(WAR/WAW)** 제거 |
| 명령어 윈도 (이슈 큐) | 연산 준비가 완료된 명령어의 추적 및 동적 스케줄링 |
| 실행 유닛 (ALU/FPU) | 다중 연산기들을 통한 독립 명령어 동시 병렬 연산 |
| 재정렬 버퍼 (ROB) | 비순서 연산 결과의 순차 커밋 및 **정밀 예외 복구** 보장 |

#### 한줄 요약

- **리네이밍(가짜 의존성 제거)·이슈큐(동적 스케줄링)·ROB(순차 커밋)** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **종속 명령 깨우기(Wakeup & Select)**: 선행 연산 완료 신호를 감지하여 해당 결과를 기다리던 후속 명령어의 실행 플래그를 활성화하는 과정.

</details>

```text
[ 프런트엔드 다중 명령어 인출 및 해독 ]
                  │
                  ▼
[ 레지스터 리네이밍 ] ──> WAR / WAW 가짜 의존성 제거
                  │
                  ▼
[ 이슈 큐 대기 ] ───────> 피연산자 준비 완료 시 종속 명령 깨우기
                  │
                  ▼
[ 다중 실행 유닛 ] ─────> 비순차 동시 병렬 연산 (ALU, FPU, LSU)
                  │
                  ▼
[ 재주문 버퍼 (ROB) ] ──> 프로그램 원래 순서대로 순차 커밋
```

**동작 원리**

1. **다중 인출/해독**: 단일 클록에 4~8개의 명령어를 동시에 인출하고 파싱
2. **레지스터 리네이밍**: 물리 레지스터 테이블(RAT)을 활용해 WAR(쓰기 후 읽기) 및 WAW(쓰기 후 쓰기) 가짜 의존성 제거
3. **깨우기 및 선택**: 이슈 큐에서 피연산자가 모두 준비된 명령어를 즉시 깨워 가용한 연산기로 발행
4. **비순차 실행**: 연산 준비가 끝난 독립 명령어들을 ALU, FPU, LSU에서 병렬 연산
5. **순차 커밋**: ROB의 맨 앞(Head)부터 원래 순서대로 결과를 확정하여 예외 및 인터럽트 안전성 보장

#### 한줄 요약

- **인출-리네이밍-비순차 실행-순차 커밋(ROB)**의 일관성 보장 흐름

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **ILP vs TLP vs DLP**:
  - ILP: 단일 스레드 내 명령어 병렬화
  - TLP: 멀티스레드/멀티코어 기반 태스크 병렬화
  - DLP: 대규모 데이터 배열에 대한 벡터/SIMD 병렬화

</details>

| 병렬성 분류 | 명령어 수준 병렬성 (ILP) | 스레드 수준 병렬성 (TLP) | 데이터 수준 병렬성 (DLP) |
|:---|:---|:---|:---|
| 적용 기준 | 단일 스레드 내 독립 연산 다중화 | 다중 태스크/스레드 동시 실행 | 대용량 행렬/미디어 데이터 일괄 연산 |
| 핵심 특징 | 슈퍼스칼라, 비순차 실행(OoO), VLIW | 멀티코어, 동시 멀티스레딩(SMT) | SIMD, 벡터 프로세서, GPU/NPU |
| 한계 및 위험 | 분기/데이터 의존성 및 하드웨어 복잡도 | 스레드 동기화 오버헤드, 락 경합 | 분기 발산(Divergence), 메모리 정렬 제약 |

#### 한줄 요약

- **단일 스레드(ILP)·멀티태스크(TLP)·대규모 데이터(DLP)**로 병렬화 계층 분화

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **루프 언롤링(Loop Unrolling)**: 반복문 본체를 여러 번 펼쳐 분기 오버헤드를 줄이고 명령어 간 병렬성을 확장하는 컴파일러 최적화.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 반복문의 긴 **쓰기 후 읽기 의존 사슬**로 연산기 유휴 상태 유발 | **다중 누산기** 분할 및 반복문 전개 최적화 적용 | 데이터 사슬 단축 및 실행 유닛 활용률 극대화 |
| 논리 레지스터 부족에 따른 명령어 리네이밍 정체 | 확장된 **물리 레지스터 리네이밍** 자원 구성 | 가짜 데이터 의존 완화 및 명령어 공급 정체 해소 |
| 확장 발행 폭에 따른 탐색 면적 증가와 동적 전력 폭증 | 동적 **클록 게이팅** 및 윈도 적정 크기 최적화 | 지정 전력 한도 내 초고속 동작 주파수 유지 달성 |
| 캐시 미스로 인한 잦은 **프런트엔드 병목** 단절 현상 | 미세 연산 캐시 탑재 및 고급 분기 예측기 구현 | 명령어 대기열 공급 중단 빈도 최소화 |

#### 한줄 요약

- **루프 언롤링·물리 레지스터 확장·클록 게이팅**으로 병목 및 전력 제어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ILP 벽(ILP Wall)**: 복잡도와 발열(Power Wall)로 인해 단일 코어의 ILP 확장이 한계에 부딪혀 멀티코어/가속기로 패러다임이 전환된 현상.

</details>

- ILP 벽(ILP Wall) 극복을 위한 **멀티코어(TLP) 및 도메인 특화 가속기(DLP)로의 아키텍처 전환**

#### 한줄 요약

- **ILP 한계 도달 시 TLP 및 가속기(DLP)**로 병렬 컴퓨팅 패러다임 확장
