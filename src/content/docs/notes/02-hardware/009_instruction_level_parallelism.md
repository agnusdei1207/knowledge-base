## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism)**: 단일 프로그램 스레드 내에서 의존성이 없는 독립적인 명령어들을 동일 주기에 다중 파이프라인에서 동시 처리하는 병렬 기법이다.
- **클록당 명령어 수(Instructions Per Cycle)**: 프로세서가 단일 클록 주기에 처리하여 확정하는 평균 명령어 수이다.
- **실행 유닛(Execution Unit)**: 파이프라인 내부에서 독립적 연산을 동시 수행하는 물리적 하드웨어 블록이다.

</details>

- 정의: 단일 스레드 내에서 의존성이 없는 명령어들을 탐지하여 다중 파이프라인에서 동시 처리하는 프로세서 하드웨어 **명령어 수준 병렬성** 기법
- 배경: 단순 순차 실행 시 데이터 지연으로 인해 발생하는 **실행 유닛** 유휴 상태와 **클록당 명령어 수** 저하를 해결하기 위함

#### 한줄 요약

- 단일 스레드의 상호 독립된 기계어 명령어를 다중 파이프라인에 동시 발행하여 단일 스레드 처리량을 극대화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **슈퍼스칼라(Superscalar)**: 단일 클록 주기에 복수의 명령어를 동시 인출, 해독, 발행할 수 있도록 다중 데이터 경로를 구축한 아키텍처이다.
- **비순서 실행(Out-of-Order Execution)**: 연산 준비가 끝난 독립 명령어부터 순서와 다르게 먼저 계산하되 결과는 순서대로 저장하는 기술이다.
- **발행 폭(Issue Width)**: 프로세서가 단일 클록 주기에 연산기로 보낼 수 있는 최대 명령어 수이다.
- **발행 슬롯 활용률(Issue Slot Utilization)**: 제공되는 발행 슬롯 중 실제 유효 명령어가 할당되어 연산에 투입된 비율이다.
- **순차 커밋(In-Order Commit)**: 비순서 연산 결과를 재정렬 버퍼를 통해 원래 프로그램 순서대로 반영하는 기법이다.

</details>

- 데이터 의존성, 조건 분기 실패, 캐시 지연이 **발행 슬롯 활용률**을 저하시키는 주요 원인임.
- 다중 인출 디코더와 연산기를 탑재한 **슈퍼스칼라** 기법을 통해 **발행 폭**을 확장함.
- **비순서 실행**과 **순차 커밋**을 결합하여 정밀 예외와 프로그램 순차 상태를 유지함.

#### 한줄 요약

- 슈퍼스칼라 다중 발행 구조와 비순서 엔진을 활용하여 의존성 없는 독립 명령어를 동시에 병렬 처리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터 리네이밍(Register Renaming)**: 소수의 아키텍처 레지스터를 다수의 물리 레지스터에 매핑하여 가짜 의존성을 제거하는 기술이다.
- **명령어 윈도(Instruction Window)**: 기계어들이 적재되어 피연산자의 연산 준비 완료 여부를 실시간 추적하고 스케줄링하는 대기열이다.
- **재정렬 버퍼(Reorder Buffer)**: 비순서 결과를 임시 보관하여 원래 순서대로 확정시키는 원형 큐 버퍼이다.
- **프런트엔드(Frontend)**: 분기 예측기와 디코더로 구성되어 파이프라인에 명령어 후보를 지속적으로 공급하는 장치이다.
- **읽기 후 쓰기 의존(Write After Read)**: 앞 명령어가 읽기 전 뒤 명령어가 쓰기를 수행하려는 가짜 데이터 의존성이다.
- **쓰기 후 쓰기 의존(Write After Write)**: 쓰기 명령어 간의 완료 순서 교란으로 최종 결과가 덮어씌워지는 가짜 의존성이다.
- **정밀 복구(Precise Recovery)**: 예외 발생 시 순차 커밋 지점까지 상태만 보존하고 이후 비순서 결과를 무효화하는 하드웨어 보장 체계이다.
- **물리 레지스터 파일(Physical Register File)**: 가짜 의존성을 제거하고 다수의 명령어를 병렬 실행하도록 지원하는 확장 레지스터이다.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 프런트엔드 | 분기 예측, 다중 인출 및 해독 수행 |
| 레지스터 리네이밍 | 물리 레지스터 매핑으로 **읽기 후 쓰기 의존**과 **쓰기 후 쓰기 의존** 제거 |
| 명령어 윈도 | 연산 준비가 완료된 명령어의 추적 및 선택 수행 |
| 실행 유닛 | 내부 연산기들을 통한 다중 명령 병렬 연산 수행 |
| 재정렬 버퍼 | 비순서 연산 결과의 순차 커밋 및 **정밀 복구** 보장 |

#### 한줄 요약

- 레지스터 리네이밍으로 가짜 의존성을 제거하고 명령어 윈도와 재정렬 버퍼를 통해 비순서 실행 및 순차 확정을 달성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **종속 명령 깨우기(Wakeup & Select)**: 연산 완료 후 결과를 기다리던 내부 명령어 활성화 비트를 켜는 스케줄링 제어 장치이다.
- **비순서 발행(Out-of-Order Issue)**: 프로그램의 순서와 무관하게 연산 피연산자가 모두 준비된 명령어를 즉시 하드웨어 연산기로 보내는 방식이다.

</details>

```text
[ 프런트엔드 및 인출 ]
        │
        ▼
[ 레지스터 리네이밍 ] ──> 가짜 의존성 제거
        │
        ▼
[ 명령어 윈도 대기 ] ──> 종속 명령 깨우기
        │
        ▼
[ 비순서 실행 유닛 ] ──> 비순서 발행 및 병렬 연산
        │
        ▼
[ 재정렬 버퍼 ] ──> 순차 커밋 및 확정
```

### 동작 원리

1. 인출 및 해독: 정해진 발행 폭만큼 명령어 후보를 연속으로 공급함.
2. 레지스터 리네이밍: 물리 레지스터 매핑으로 가짜 의존성을 제거함.
3. 깨우기 및 선택: 피연산자가 준비된 명령어의 **종속 명령 깨우기**를 우선으로 선택함.
4. 비순서 실행: 준비된 순서에 따라 연산 유닛들에 **비순서 발행**을 수행함.
5. 순차 커밋: 재정렬 버퍼의 선두부터 순서대로 연산 결과와 상태를 반영함.

#### 한줄 요약

- 리네이밍 후 준비가 완료된 명령을 비순서로 우선 실행하고 재정렬 버퍼를 거쳐 순차적으로 상태를 확정한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **스레드 수준 병렬성(Thread-Level Parallelism)**: 멀티코어 환경에서 독립적인 소프트웨어 스레드를 동시에 구동하는 병렬 기법이다.
- **데이터 수준 병렬성(Data-Level Parallelism)**: 단일 명령어로 대량의 데이터 배열 항목을 병렬 연산하는 기법이다.
- **동적 ILP(Dynamic ILP)**: 실행 중 하드웨어가 직접 명령어 간 병렬성을 추출하는 방식이다.
- **정적 ILP(Static ILP)**: 컴파일러가 빌드 시점에 긴 묶음 기계어로 명령어 순서를 재배치하는 방식이다.
- **매우 긴 명령어(Very Long Instruction Word)**: 컴파일러가 독립 연산을 하나의 큰 명령어 묶음으로 편성하는 구조이다.

</details>

| 비교 항목 | 명령어 수준 병렬성 | 스레드 수준 병렬성 | 데이터 수준 병렬성 |
|:---|:---|:---|:---|
| 병렬성 주체 | 스레드 내부 독립 명령어 단위 병렬 | 독립적인 소프트웨어 스레드 단위 병렬 | 대량 데이터 배열 단위 다중 데이터 병렬 |
| 하드웨어 구현 | 슈퍼스칼라 비순서 실행 엔진 적용 | 멀티코어 기반 동시 멀티스레딩 적용 | 벡터 프로세서 및 다중 단일 명령어 데이터 연산기 적용 |
| 주요 한계 | 명령어 간 진성 데이터 의존성 병목 | 메모리 동기화 및 락 자원 경합 병목 | 분기 발산 및 비정렬 메모리 접근 제약 |

| 스케줄링 항목 | 동적 명령어 병렬성 | 정적 명령어 병렬성 |
|:---|:---|:---|
| 주요 하드웨어 | 비순서 실행 엔진 및 명령어 윈도 | 컴파일러 종속적 다중 연산기 및 **매우 긴 명령어** 구조 |
| 호환성 여부 | 동일 아키텍처 간 바이너리 호환성 우수 | 발행 폭 변경 시 타깃 재컴파일 요구 빈발 |
| 회로 복잡도 | 높은 탐색 비용 및 하드웨어 면적 필요 | 하드웨어 제어 회로 최소화로 전력 절약 |

#### 한줄 요약

- 명령어 병렬성은 단일 스레드를 처리하며 다중 스레드나 대량 데이터 병렬성 대비 목적이 다르고 동적과 정적 모델로 구분된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쓰기 후 읽기 의존 사슬(RAW Dependency Chain)**: 연산 결과가 다음 피연산자로 계속 이어져 병렬 추출을 저해하는 현상이다.
- **다중 누산기(Multiple Accumulators)**: 반복문 내 연산 사슬을 독립 레지스터 변수로 분할 연산 후 합산하여 의존성을 짧게 줄이는 기법이다.
- **프런트엔드 병목(Frontend Bottleneck)**: 인출 지연이나 대역폭 한계로 대기열에 충분한 기계어 후보가 적재되지 못하는 현상이다.
- **물리 레지스터 리네이밍(Physical Register Renaming)**: 레지스터 개수를 늘려 가짜 의존성 제거율을 상승시키는 기술이다.
- **클록 게이팅(Clock Gating)**: 유휴 상태인 회로 블록의 클록 신호를 차단하여 동적 전력을 대폭 절감하는 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 반복문의 긴 **쓰기 후 읽기 의존 사슬**로 연산기 유휴 상태 유발 | **다중 누산기** 분할 및 반복문 전개 최적화 적용 | 데이터 사슬 단축 및 실행 유닛 활용률 극대화 |
| 논리 레지스터 부족에 따른 명령어 리네이밍 정체 | 확장된 **물리 레지스터 리네이밍** 자원 구성 | 가짜 데이터 의존 완화 및 명령어 공급 정체 해소 |
| 확장 발행 폭에 따른 탐색 면적 증가와 동적 전력 폭증 | 동적 **클록 게이팅** 및 윈도 적정 크기 최적화 | 지정 전력 한도 내 초고속 동작 주파수 유지 달성 |
| 캐시 미스로 인한 잦은 **프런트엔드 병목** 단절 현상 | 미세 연산 캐시 탑재 및 고급 분기 예측기 구현 | 명령어 대기열 공급 중단 빈도 최소화 |

#### 한줄 요약

- 다중 누산기, 물리 레지스터 확장, 클록 차단, 분기 예측 개선으로 병렬 추출 한계와 전력 오버헤드를 동시에 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **임계 경로(Critical Path)**: 직렬로 연결된 가장 긴 의존 사슬로 단일 스레드의 теорети적 최고 병렬성 한계이다.
- **병렬성 전환 기준(Parallelism Shift Criteria)**: 명령어 병렬성 확장이 한계에 도달했을 때 다중 스레드나 데이터 병렬로 전환을 결정하는 기준이다.

</details>

- **병렬성 전환 기준**에 따라 명령어 확장이 한계에 도달하면 다중 스레드 또는 데이터 병렬 모델로 구조를 전환함

#### 한줄 요약

- 의존성 임계 경로 한계와 하드웨어 전력 소모를 기준으로 각 단계에 적합한 병렬성 구조를 유연하게 선택해야 한다.
