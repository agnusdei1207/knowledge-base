## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism, ILP)**: 한 스레드의 독립 명령어를 중첩하거나 동시에 실행하는 병렬성
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 프로세서가 한 클록에 완료하는 평균 명령어 수
- **실행 유닛** 은 산술•논리•메모리 접근 등 명령의 실제 연산을 수행하는 하드웨어 장치이다.

</details>

- 정의/개념: **ILP** 는 한 스레드의 독립 명령들을 동시에 실행하는 **단일 스레드 병렬성**
- 배경/필요성: 순차 발행은 독립 명령에도 **실행 유닛 유휴** 발생

#### 한줄 요약
- 앞 단계를 기다리지 않는 작업을 양손으로 함께 처리한다

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **슈퍼스칼라** 는 한 클록 주기에 여러 명령을 발행할 수 있도록 복수 실행 경로를 둔 프로세서 구조이다.
- **비순서 실행** 은 피연산자가 준비된 명령부터 실행하되 결과는 프로그램 순서대로 확정한다.
- **발행 폭** 은 한 주기에 실행 유닛으로 보낼 수 있는 최대 명령어 수이다.
- **발행 슬롯 활용률** 은 한 주기에 가능한 발행 자리 중 실제 명령이 사용한 비율이다.
- **순차 커밋** 은 비순서로 완료된 결과를 원래 프로그램 순서대로 아키텍처 상태에 확정하는 방식이다.

</details>

- 의존 사슬•분기 실패•메모리 지연이 **발행 슬롯 활용률** 제한
- 복수 발행 **슈퍼스칼라** 로 동시 실행 폭 확대
- **비순서 실행•순차 커밋** 으로 아키텍처 상태 보존

#### 한줄 요약
- 손이 많아도 선후 관계나 재료 대기가 남으면 동시 작업은 늘지 않는다

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **레지스터 리네이밍**: 논리 레지스터를 물리 레지스터에 매핑해 가짜 의존성을 제거하는 기법
- **명령어 윈도** 는 명령의 피연산자 준비 상태를 추적하고 실행 가능한 명령을 선택하는 대기 영역이다.
- **재정렬 버퍼(Reorder Buffer, ROB)**: 비순서 실행 결과를 순서대로 커밋하고 상태를 복구하는 버퍼
- **프런트엔드** 는 명령을 예측•인출•해독해 후속 실행 단계에 공급하는 처리부이다.
- **읽기 후 쓰기(Write After Read, WAR) 의존**: 선행 읽기 전에 후행 쓰기가 같은 위치를 덮는 가짜 의존
- **쓰기 후 쓰기(Write After Write, WAW) 의존**: 두 쓰기의 완료 순서가 바뀌는 가짜 의존
- **정밀 복구** 는 예외나 오예측 이전까지 확정된 상태만 보존하고 이후 명령의 효과를 제거하는 처리이다.

</details>

```text
[프런트엔드] -- [레지스터 리네이밍] -- [명령어 윈도]
                                               |
                             [재정렬 버퍼] -- [실행 유닛]
```

선의 의미: 명령 공급•물리 레지스터 매핑•발행 대기•실행•순차 확정을 담당하는 하드웨어 블록 사이의 정적 인터페이스 연결 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 프런트엔드 | 예측•인출•해독으로 **후보 공급** |
| 레지스터 리네이밍 | WAR•WAW **가짜 의존 제거** |
| 명령어 윈도 | 실행 가능한 **발행 대상 선택** |
| 실행 유닛 | 산술•메모리 **연산 수행** |
| 재정렬 버퍼 | 순차 확정과 **정밀 복구** |

#### 한줄 요약
- 후보 공급 후 **비순서 실행**, 재정렬 버퍼에서 순서 복원

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **순차 커밋** 은 비순서로 완료된 명령 결과를 원래 프로그램 순서대로 아키텍처 상태에 반영한다.
- **정밀 복구** 는 예외나 오예측 이전의 확정 상태만 보존하고 이후 명령의 효과를 제거한다.
- **종속 명령 깨우기** 는 생산 명령의 결과가 준비됐음을 알려 그 값을 기다리던 명령을 발행 가능 상태로 바꾸는 동작이다.
- **비순서 발행** 은 프로그램 순서와 관계없이 피연산자가 준비된 명령을 실행 유닛으로 보내는 방식이다.

</details>

```text
                [인출•해독 명령]
                         |
              1. 리네이밍•의존 등록
                         |
                  [명령어 윈도]
                         |
                [피연산자 준비?]
                   /           \
                [아니요]       [예]
                   |             |
              [윈도 대기]   2. 준비 명령 비순서 발행
                   ^             |
                   |       3. 실행•결과 기록
                   |             |
                   +----[종속 명령 깨우기]
                                 |
                      [ROB 선두 명령 판정]
                           /             \
                    [정상 완료]      [예외•오예측]
                         |                 |
                  4. 순차 커밋       5. 결과 폐기•복구
                         |                 |
                    [상태 확정]       [정상 경로 재개]
```

**동작 원리**

- **1. 리네이밍•의존 등록**: 가짜 의존 제거와 ROB 할당
- **2. 준비 명령 비순서 발행**: 준비 연산을 실행 유닛에 배치
- **3. 실행•결과 기록**: 완료 표시와 종속 명령 깨우기
- **4. 순차 커밋**: 프로그램 순서대로 상태 확정
- **5. 결과 폐기•복구**: 이후 명령 제거와 정상 경로 재개

#### 한줄 요약
- 여러 일을 먼저 끝내도 번호표 순서대로 결과를 내놓는다

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 독립적인 여러 스레드를 동시에 실행하는 병렬성
- **데이터 수준 병렬성(Data-Level Parallelism, DLP)**: 여러 데이터 원소에 같은 연산을 동시에 적용하는 병렬성
- **동적 ILP**: 하드웨어가 실행 중 독립 명령의 순서를 정하는 방식
- **정적 ILP**: 컴파일러가 실행 전에 독립 연산을 배치하는 방식
- **제어 의존성** 은 분기 결과에 따라 후속 명령의 실행 여부나 경로가 달라지는 관계이다.
- **분기 발산**: 데이터별 실행 경로가 갈려 DLP 효율을 낮추는 조건
- **불규칙 접근**: 메모리 주소 패턴이 일정하지 않아 DLP 효율을 낮추는 조건
- **매우 긴 명령어(very long instruction word, VLIW)**: 여러 연산을 긴 명령어에 묶는 정적 ILP 방식
- **이진 호환성** 은 기존에 컴파일한 실행 파일을 변경 없이 같은 ISA 환경에서 실행할 수 있는 성질이다.

</details>

| 판단 기준 | ILP | TLP | DLP |
|:---|:---|:---|:---|
| 적용 기준 | 독립 명령이 충분한 **단일 스레드** | 독립 **작업•요청** 이 충분한 경우 | 규칙적 데이터에 **동일 연산** 을 반복하는 경우 |
| 핵심 특징 | 한 스레드의 **독립 명령** | 서로 독립적인 **스레드** | 같은 연산의 여러 **데이터** |
| 한계 | 데이터•**제어 의존성** | 동기화•**공유 자원 경합** | 분기 발산•**불규칙 접근** |

> 요약: 지연은 ILP, 작업은 TLP, 배열은 DLP

| 판단 기준 | 동적 ILP | 정적 ILP |
|:---|:---|:---|
| 적용 기준 | 가변 지연과 **기존 바이너리** 대응이 필요한 경우 | 규칙적 연산을 **재컴파일**할 수 있는 경우 |
| 핵심 특징 | **하드웨어** 가 실행 중 스케줄 | **컴파일러•VLIW** 가 실행 전 스케줄 |
| 한계 | 탐색 회로 **면적•전력** | 빈 슬롯•**이진 호환성** |

> 요약: 가변 지연은 동적, 규칙 연산은 정적 ILP

#### 한줄 요약
- 양손 작업은 ILP, 요리사 분담은 TLP, 같은 재료 묶음은 DLP에 해당한다

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **쓰기 후 읽기(Read After Write, RAW) 의존 사슬**: 선행 결과가 연속해서 후행 입력이 되는 실제 의존 사슬
- **다중 누산기** 는 합산 결과를 여러 독립 레지스터에 나누어 하나의 긴 RAW 의존 사슬을 짧게 만든다.
- **클록 게이팅** 은 사용하지 않는 회로 블록의 클록 공급을 차단하여 동적 전력을 줄인다.
- **프런트엔드 병목**: 명령 공급 속도가 실행 유닛의 처리 능력을 제한하는 상태
- **메모리 병목**: 데이터 접근 속도가 실행 유닛의 처리 능력을 제한하는 상태
- **물리 레지스터 리네이밍** 은 더 많은 물리 저장소를 논리 레지스터에 배정해 WAR•WAW 의존을 제거한다.
- **실행 유닛 활용률** 은 실행 유닛이 실제 연산을 수행한 시간의 비율이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 발행 폭을 늘려도 **IPC 정체** | **의존 사슬•프런트엔드** 와 메모리 병목 분석 | 유효한 **확장 지점** 식별 |
| **WAR•WAW** 로 독립 명령 대기 | **물리 레지스터 리네이밍** 확대 | **가짜 의존** 제거 |
| 큰 **명령어 윈도** 의 전력•면적 증가 | 윈도 크기•발행 폭•**클록 게이팅** 조정 | **성능 대비 자원 효율** 향상 |
| 오예측•예외 후 **잘못된 결과 확정** | **ROB 순차 커밋•정밀 복구** 검증 | **아키텍처 상태 정확성** 유지 |
| 누산 연산의 긴 **RAW 의존 사슬** | **다중 누산기** 로 합산 후 최종 결합 | 독립 연산과 **실행 유닛 활용률** 증가 |

#### 한줄 요약
- **IPC•임계 의존 사슬** 측정과 다중 누산기 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **임계 경로** 는 프로그램에서 가장 긴 실제 데이터 의존 사슬이며 한 스레드가 활용할 수 있는 ILP의 상한을 결정한다.
- **발행 슬롯** 은 한 클록에 실행 유닛으로 보낼 수 있도록 마련된 명령 발행 자리이다.

</details>

- **IPC•발행 슬롯•임계 경로** 포화 시 TLP•DLP 확대

#### 한줄 요약
- 한 사람의 동시 작업이 한계면 사람과 작업 묶음을 늘린다
