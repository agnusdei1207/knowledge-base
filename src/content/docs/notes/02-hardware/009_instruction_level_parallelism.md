## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism, ILP)**: 한 스레드의 독립 명령어를 중첩하거나 동시에 실행하는 병렬성이다.
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 프로세서가 한 클록에 완료하는 평균 명령어 수이다.
- **실행 유닛**: 산술·논리·메모리 접근 등 명령의 실제 연산을 수행하는 하드웨어 장치이다.

</details>

- 정의/개념: **ILP**는 한 스레드의 독립 명령들을 중첩하거나 동시에 실행하는 병렬성이다.
- 배경/필요성: 순차 발행은 독립 명령이 있어도 **실행 유닛**을 유휴 상태로 두어 **IPC**를 제한한다.

#### 한줄 요약
- Data-Independent Instructions를 Superscalar Issue Width만큼 Multiple Execution Units에 동시 Dispatch하여 Single-thread IPC를 극대화한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **슈퍼스칼라**: 한 클록 주기에 여러 명령을 발행하도록 복수 실행 경로를 둔 프로세서 구조이다.
- **비순서 실행**: 피연산자가 준비된 명령부터 실행하되 결과는 프로그램 순서대로 확정하는 방식이다.
- **발행 폭**: 한 주기에 실행 유닛으로 보낼 수 있는 최대 명령어 수이다.
- **발행 슬롯 활용률**: 한 주기의 발행 자리 중 실제 명령이 사용한 비율이다.
- **순차 커밋**: 비순서로 완료된 결과를 원래 프로그램 순서대로 아키텍처 상태에 확정하는 방식이다.

</details>

- 의존 사슬•분기 실패•메모리 지연이 **발행 슬롯 활용률**을 제한한다.
- 복수 발행 **슈퍼스칼라**로 동시 실행 폭을 확대한다.
- **발행 폭**을 늘리되 **발행 슬롯 활용률**로 실제 사용 정도를 확인한다.
- **비순서 실행**•**순차 커밋**으로 병렬 실행과 정확한 상태 확정을 양립시킨다.

#### 한줄 요약
- Issue Width를 확장해도 RAW Dependency Chain, Branch Misprediction, Memory Latency에 의해 Issue Slot Utilization이 제한된다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **레지스터 리네이밍**: 논리 레지스터를 물리 레지스터에 매핑해 가짜 의존성을 제거하는 기법이다.
- **명령어 윈도**: 명령의 피연산자 준비 상태를 추적하고 실행 가능한 명령을 선택하는 대기 영역이다.
- **재정렬 버퍼(Reorder Buffer, ROB)**: 비순서 실행 결과를 순서대로 커밋하고 상태를 복구하는 버퍼이다.
- **프런트엔드**: 명령을 예측·인출·해독해 후속 실행 단계에 공급하는 처리부이다.
- **읽기 후 쓰기(Write After Read, WAR) 의존**: 선행 읽기 전에 후행 쓰기가 같은 위치를 덮는 가짜 의존이다.
- **쓰기 후 쓰기(Write After Write, WAW) 의존**: 두 쓰기의 완료 순서가 바뀌는 가짜 의존이다.
- **정밀 복구**: 예외나 오예측 이전까지 확정된 상태만 보존하고 이후 명령의 효과를 제거하는 처리이다.

</details>

```text
ILP 실행 구조
├─ 프런트엔드
├─ 레지스터 리네이밍
├─ 명령어 윈도
├─ 실행 유닛
└─ 재정렬 버퍼
```

가지의 의미: 명령 공급부터 순차 확정까지의 정적 책임 구성이다.

| 구성요소 | 책임 |
|:---|:---|
| **프런트엔드** | 예측•인출•해독으로 후보 공급 |
| **레지스터 리네이밍** | **WAR 의존**•**WAW 의존** 제거 |
| **명령어 윈도** | 실행 가능한 발행 대상 선택 |
| **실행 유닛** | 산술•메모리 연산 수행 |
| **재정렬 버퍼** | 순차 확정과 **정밀 복구** |

#### 한줄 요약
- 프런트엔드가 후보를 공급하고 리네이밍•윈도•실행 유닛이 병렬 처리하며 재정렬 버퍼가 순서를 복원한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **순차 커밋**: 비순서로 완료된 명령 결과를 원래 프로그램 순서대로 아키텍처 상태에 반영하는 방식이다.
- **정밀 복구**: 예외나 오예측 이전의 확정 상태만 보존하고 이후 명령의 효과를 제거하는 처리이다.
- **종속 명령 깨우기**: 생산 명령의 결과가 준비됐음을 알려 대기 명령을 발행 가능 상태로 바꾸는 동작이다.
- **비순서 발행**: 프로그램 순서와 관계없이 피연산자가 준비된 명령을 실행 유닛으로 보내는 방식이다.
- **명령 인출•해독 결과 전달**: 예측 경로에서 인출•해독한 명령을 리네이밍 단계에 공급하는 단계이다.
- **리네이밍 명령•의존 정보 전달**: 물리 레지스터를 배정하고 실제 의존 정보를 명령어 윈도에 보내는 단계이다.
- **준비 명령 전달**: 피연산자가 준비된 명령을 비순서로 실행 유닛에 발행하는 단계이다.
- **실행 결과•완료 상태 전달**: 실행 결과를 기록하고 종속 명령을 깨우는 단계이다.
- **순차 커밋•복구**: 프로그램 순서대로 결과를 확정하거나 오예측•예외 이후 결과를 폐기하는 단계이다.

</details>

```text
1. 명령 인출•해독 결과 전달
              │
              ▼
2. 리네이밍 명령•의존 정보 전달
              │
              ▼
피연산자가 준비된 명령이 있는 동안
├─ 3. 준비 명령 전달
├─ 4. 실행 결과•완료 상태 전달
└─ 종속 명령 깨우기 후 반복
              │
              ▼
        완료 상태 판정
              ├─ 정상: 순차 상태 확정
              └─ 오예측•예외: 이후 결과 폐기
                         │
                         ▼
                5. 순차 커밋•복구
```

### 동작 원리

1. **명령 인출·해독 결과 전달**: 예측 경로의 해독 명령을 리네이밍 단계에 공급한다.
2. **리네이밍 명령·의존 정보 전달**: 물리 레지스터를 배정해 WAR·WAW을 제거한다.
3. **준비 명령 전달**: 피연산자가 준비된 명령을 **비순서 발행**으로 실행 유닛에 보낸다.
4. **실행 결과·완료 상태 전달**: 결과를 기록하고 의존 명령을 실행 가능 상태로 전환한다.
5. **순차 커밋•복구**: **정밀 복구**로 프로그램 순서대로 상태를 확정하거나 후속 결과를 폐기한다.

#### 한줄 요약
- Out-of-Order Execution으로 완료된 결과를 Reorder Buffer(ROB)를 통해 Program Order대로 In-order Commit한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 독립적인 여러 스레드를 동시에 실행하는 병렬성이다.
- **데이터 수준 병렬성(Data-Level Parallelism, DLP)**: 여러 데이터 원소에 같은 연산을 동시에 적용하는 병렬성이다.
- **동적 ILP**: 하드웨어가 실행 중 독립 명령의 순서를 정하는 방식이다.
- **정적 ILP**: 컴파일러가 실행 전에 독립 연산을 배치하는 방식이다.
- **제어 의존성**: 분기 결과에 따라 후속 명령의 실행 여부나 경로가 달라지는 관계이다.
- **분기 발산**: 데이터별 실행 경로가 갈려 DLP 효율을 낮추는 조건이다.
- **불규칙 접근**: 메모리 주소 패턴이 일정하지 않아 DLP 효율을 낮추는 조건이다.
- **매우 긴 명령어(very long instruction word, VLIW)**: 여러 연산을 긴 명령어에 묶는 정적 ILP 방식이다.
- **이진 호환성**: 기존에 컴파일한 실행 파일을 변경 없이 같은 ISA 환경에서 실행할 수 있는 성질이다.
- **공유 자원 경합**: 여러 스레드가 같은 캐시•메모리•실행 자원을 동시에 요구해 대기하는 현상이다.

</details>

| 병렬성 수준 | ILP | TLP | DLP |
|:---|:---|:---|:---|
| 적용 기준 | 한 스레드 안에 독립 명령이 충분할 때 | 독립 작업•요청이 충분할 때 | 규칙적 데이터에 동일 연산을 반복할 때 |
| 핵심 특징 | **ILP**로 한 스레드의 명령 병렬화 | **TLP**로 여러 스레드 병렬화 | **DLP**로 여러 데이터 병렬화 |
| 한계 | 데이터•**제어 의존성** | 동기화•**공유 자원 경합** | **분기 발산**•**불규칙 접근** |

> 요약: 지연은 ILP, 작업은 TLP, 배열은 DLP가 핵심이다.

| ILP 스케줄링 | 동적 ILP | 정적 ILP |
|:---|:---|:---|
| 적용 기준 | 가변 지연과 기존 바이너리 대응이 필요한 경우 | 규칙적 연산을 재컴파일할 수 있는 경우 |
| 핵심 특징 | **동적 ILP**로 하드웨어가 실행 중 스케줄 | **정적 ILP**•**VLIW**로 컴파일러가 실행 전 스케줄 |
| 한계 | 탐색 회로의 면적•전력 | 빈 슬롯•**이진 호환성** |

> 요약: 가변 지연은 동적, 규칙 연산은 정적 ILP가 핵심이다.

#### 한줄 요약
- ILP는 Single-thread Instruction Overlap, TLP는 Multi-thread Concurrent Execution, DLP는 SIMD/Vector Parallel Data Operation으로 구분된다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **쓰기 후 읽기(Read After Write, RAW) 의존 사슬**: 선행 결과가 연속해서 후행 입력이 되는 실제 의존 사슬이다.
- **다중 누산기**: 합산 결과를 여러 독립 레지스터에 나누어 하나의 긴 RAW 의존 사슬을 짧게 만드는 구조이다.
- **클록 게이팅**: 사용하지 않는 회로 블록의 클록 공급을 차단하여 동적 전력을 줄이는 기법이다.
- **프런트엔드 병목**: 명령 공급 속도가 실행 유닛의 처리 능력을 제한하는 상태이다.
- **메모리 병목**: 데이터 접근 속도가 실행 유닛의 처리 능력을 제한하는 상태이다.
- **물리 레지스터 리네이밍**: 더 많은 물리 저장소를 논리 레지스터에 배정해 WAR•WAW 의존을 제거하는 기법이다.
- **실행 유닛 활용률**: 실행 유닛이 실제 연산을 수행한 시간의 비율이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 발행 폭을 늘려도 IPC 정체 | **RAW 의존 사슬**•**프런트엔드 병목**•**메모리 병목** 분석 | 유효한 확장 지점 식별 |
| WAR•WAW로 독립 명령이 대기 | **물리 레지스터 리네이밍** 확대 | 발행 가능 명령 증가 |
| 큰 **명령어 윈도**로 탐색 전력•면적 증가 | 윈도 크기•발행 폭•**클록 게이팅** 조정 | 탐색 회로 비용 억제 |
| 오예측•예외 뒤 후속 결과가 잘못 확정될 위험 | **ROB**의 **순차 커밋**•**정밀 복구** 검증 | 예외 이전 상태 보존 |
| 누산 연산의 긴 **RAW 의존 사슬** | **다중 누산기**로 부분 합산 후 결합 | **실행 유닛 활용률** 증가 |

#### 한줄 요약
- IPC•발행 슬롯•임계 의존 사슬을 함께 측정하고, 긴 누산 의존은 여러 누산기로 나눠 실행 유닛 활용률을 높인다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **임계 경로**: 프로그램에서 가장 긴 실제 데이터 의존 사슬이며 한 스레드가 활용할 수 있는 ILP의 상한을 결정한다.
- **발행 슬롯**: 한 클록에 실행 유닛으로 보낼 수 있도록 마련된 명령 발행 자리이다.
- **병렬성 전환 기준**: IPC 정체 원인이 ILP 임계 경로인지 작업•데이터 병렬성 부족인지 구분하는 기준이다.

</details>

- **병렬성 전환 기준**에 따라 **발행 슬롯**을 늘려도 **IPC**가 **임계 경로**에 막히면 작업 독립성에 따라 **TLP**•**DLP**를 확대한다.

#### 한줄 요약
- 한 스레드 안에서 더 실행할 독립 명령이 없으면 독립 스레드를 늘리거나 같은 연산을 여러 데이터에 적용하는 병렬성으로 전환한다.
