## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism, ILP)**: 하나의 스레드 안에서 서로 독립된 명령어를 동시에 실행할 수 있는 정도입니다.
- **슈퍼스칼라(Superscalar)**: 한 클록에 여러 명령어를 인출, 해독, 발행하도록 복수 실행 경로를 둔 구조입니다.
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 평균 한 클록에 완료하는 명령어의 수입니다.

</details>

- 정의/개념: 단일 프로세서 실행 파이프라인에서 상호 의존성이 없는 독립 명령어들을 동일 사이클에 동시 처리하는 **명령어 수준 병렬성(ILP) 아키텍처**
- 배경/필요성: 순차적 파이프라인 구조로는 **연산 유닛 유휴 및 데이터 의존성 대기에 따른 IPC 정체 극복 불가**

#### 한줄 요약

- ILP는 프로그램 한 줄을 여러 개로 나누는 것이 아니라, 한 스레드 안에서 서로 기다릴 필요 없는 명령어를 동시에 실행하는 방법입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비순차 실행(Out-of-Order Execution, OoO)**: 준비된 명령어를 프로그램 순서보다 먼저 실행하는 기법입니다.
- **순차 커밋(In-Order Commit)**: 실행 순서와 무관하게 결과를 프로그램 순서대로 확정하는 방식입니다.
- **발행 폭(Issue Width)**: 한 클록에 실행 후보로 보낼 수 있는 최대 명령어 수입니다.

</details>

- 발행 폭 확대에 따른 **다중 명령어 발행**
- 준비된 명령어 우선의 **비순차 실행**
- 프로그램 의미를 보존하는 **순차 커밋**

#### 한줄 요약

- 빠른 코어는 준비된 일을 먼저 처리하지만, 프로그램이 보는 결과는 원래 순서대로 확정해 정확성을 지킵니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터 리네이밍(Register Renaming)**: 아키텍처 레지스터를 물리 레지스터에 연결해 이름 때문에 생기는 의존성을 없애는 기법입니다.
- **이슈 큐(Issue Queue)**: 피연산자와 실행 유닛이 준비된 명령어를 기다리게 하는 구조입니다.
- **실행 유닛(Execution Unit)**: 산술, 부동소수점, 주소 계산처럼 명령어 연산을 실제 수행하는 회로입니다.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차 실행 결과를 보관하고 프로그램 순서의 커밋을 관리하는 구조입니다.

</details>

```text
[동적 ILP 코어]
├─ 명령어 프런트엔드
├─ 레지스터 리네이밍
├─ 이슈 큐
├─ 실행 유닛
└─ ROB
```

| 구성요소 | 책임 |
|:---|:---|
| 명령어 프런트엔드 | 명령어 인출·해독과 후보 공급 |
| 레지스터 리네이밍 | 이름 의존성 제거와 물리 레지스터 할당 |
| 이슈 큐 | 준비 상태 추적과 발행 대상 선택 |
| 실행 유닛 | 독립 명령어의 병렬 연산 수행 |
| ROB | 순차 커밋과 정확한 예외 상태 보장 |

#### 한줄 요약

- ILP 코어는 명령어를 모아 준비된 일을 고르고 여러 실행 유닛에 보내되, 결과는 순서를 지켜 확정하는 구조입니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **물리 레지스터(Physical Register)**: 리네이밍 뒤 실제 값을 보관하는 하드웨어 레지스터입니다.
- **커밋(Commit)**: 실행 결과를 프로그램이 관찰하는 상태로 확정하는 처리입니다.

</details>

```text
[ 1. 인출 및 해독 ]
        │
        ▼
[ 2. 리네이밍 및 대기 등록 ]
        │
        ▼
[ 3. 준비 명령어 발행 및 실행 ]
        │
        ▼
[ 4. ROB 순차 커밋 ]
```

**동작 원리**

1. **인출 및 해독**: 프런트엔드가 실행 후보 명령어 공급
2. **리네이밍 및 대기 등록**: 물리 레지스터 연결과 이슈 큐 등록
3. **준비 명령어 발행 및 실행**: 피연산자와 유닛이 준비된 명령어 우선 실행
4. **ROB 순차 커밋**: 앞선 명령어부터 결과와 예외를 프로그램 상태에 확정

#### 한줄 요약

- ILP는 먼저 할 수 있는 일을 앞당겨 실행하지만, 마지막 확인대에서는 원래 순서를 지켜 프로그램이 예상한 결과만 보이게 합니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **스레드 수준 병렬성(Thread-Level Parallelism, TLP)**: 여러 스레드 또는 태스크를 동시에 실행하는 병렬성입니다.
- **데이터 수준 병렬성(Data-Level Parallelism, DLP)**: 같은 연산을 여러 데이터 요소에 병렬 적용하는 병렬성입니다.
- **단일 명령어 다중 데이터(Single Instruction, Multiple Data, SIMD)**: 하나의 명령어로 여러 데이터 요소에 같은 연산을 수행하는 방식입니다.

</details>

| 병렬성 수준 | ILP | TLP | DLP |
|:---|:---|:---|:---|
| 적용 기준 | 한 스레드 내 독립 명령어 다수 | 독립 스레드·태스크 다수 | 동일 연산 대상 데이터 다수 |
| 핵심 특징 | 슈퍼스칼라와 OoO 실행 | 멀티코어와 동시 멀티스레딩 | SIMD·벡터·GPU 실행 |
| 한계 | 의존성·분기·메모리 지연 | 동기화와 공유 자원 경합 | 불규칙 데이터와 분기 발산 |

#### 한줄 요약

- 한 스레드의 빈틈을 찾으면 ILP, 여러 작업이 있으면 TLP, 같은 계산을 데이터 묶음에 반복하면 DLP가 맞습니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **루프 언롤링(Loop Unrolling)**: 반복 본문을 펼쳐 반복 제어 비용을 줄이고 독립 연산을 드러내는 최적화입니다.
- **클록 게이팅(Clock Gating)**: 사용하지 않는 회로에 클록 공급을 줄여 동적 전력을 낮추는 기법입니다.
- **마이크로연산 캐시(Micro-operation Cache)**: 해독한 내부 연산을 저장해 반복 실행의 해독 부담을 줄이는 캐시입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 데이터 의존 사슬로 실행 유닛 유휴 | 루프 언롤링과 알고리즘 의존성 분할 | 독립 명령어와 ILP 기회 확대 |
| 이슈 큐와 물리 레지스터 부족 | 워크로드 기준 자원 크기 조정 | 발행 정체와 면적의 균형 |
| 넓은 발행 회로의 동적 전력 증가 | 클록 게이팅과 발행 폭 제한 | 전력 예산 내 ILP 활용 |
| 해독·분기 실패로 후보 명령어 부족 | 분기 예측과 마이크로연산 캐시 적용 | 프런트엔드 공급 손실 완화 |

#### 한줄 요약

- ILP 성능은 실행 유닛만 늘려서 나오지 않으며, 독립 명령어를 만들고 공급하고 저장할 자원과 전력을 같이 맞춰야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **메모리 병목(Memory Bottleneck)**: 프로세서가 필요한 데이터를 받기 전에 메모리 접근 지연으로 대기하는 현상입니다.

</details>

- 단일 스레드 독립성은 **ILP 확대**, 메모리 지연은 **TLP/DLP 전환** 선택

#### 한줄 요약

- 명령어를 더 많이 동시에 실행해도 기다리는 데이터가 많으면 이득이 작으므로, 프로그램에 실제로 어떤 병렬성이 있는지부터 보고 자원을 투자해야 합니다.
