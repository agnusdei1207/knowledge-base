## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 레이턴시(Interrupt Latency)**: 하드웨어 인터럽트 신호가 발생한 시점부터 CPU가 해당 인터럽트 서비스 루틴(ISR)의 첫 명령어를 실행하기까지 걸리는 시간.
- **우선순위 역전(Priority Inversion)**: 고순위 태스크가 저순위 태스크가 점유한 자원을 기다리면서 실행 순서가 우선순위와 반대로 되는 현상.

</details>

- 정의/개념: 외부 이벤트 요청부터 ISR 실행까지의 **인터럽트 지연시간(하드웨어적 지연)** 과 공유 자원 경합에 따른 **우선순위 역전(소프트웨어적 지연)** 의 실시간 병목 현상
- 배경/필요성: 긴급 이벤트 응답 지연 및 고우선순위 태스크 블로킹에 따른 실시간 제어 마감시간 위반 방지 필요

#### 한줄 요약
- 하드웨어 신호가 와도 CPU가 늦게 알아채는 지연(Latency)과, 중요한 작업이 덜 중요한 작업에 밀려 멈추는 역전(Inversion) 문제다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우선순위 상속 프로토콜(Priority Inheritance Protocol, PIP)**: 공유 뮤텍스를 쥔 저순위 태스크의 우선순위를 자원을 기다리는 고순위 태스크의 우선순위로 임시 승격시키는 기법.
- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 뮤텍스마다 접근 가능한 최고 우선순위(Ceiling)를 부여하여 교착상태(Deadlock)와 연쇄 블로킹을 사전 차단하는 기법.

</details>

- **인터럽트 레이턴시**: 파이프라인 정리, 문맥 저장, 인터럽트 마스킹(비활성화) 구간에 의해 발생
- **우선순위 역전**: 중간 순위 태스크가 자원 보유자를 선점하면 고순위 태스크의 블로킹 시간 확대
- 해결책으로 **Top-Half/Bottom-Half 분리** 및 **우선순위 상속(PIP)/천장(PCP)** 프로토콜 적용

#### 한줄 요약
- 인터럽트 지연은 ISR을 초경량화해 줄이고, 우선순위 역전은 우선순위 상속/천장 프로토콜로 임시 승격시켜 해결한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Top-Half / Bottom-Half**: 인터럽트 직후 즉각 처리해야 하는 최소 하드웨어 작업(Top-Half)과 지연 처리 가능한 본 작업(Bottom-Half)으로 나누는 기법.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 우선순위 역전(Priority Inversion) 발생 및 PIP 해결 메커니즘 │
│                                                             │
│  [ 우선순위 역전 문제 상황 ]                                │
│  태스크 H (High)  :         ───► [뮤텍스 대기 Blocked!!]───►│
│  태스크 M (Medium):                  [── 선점 실행 ──]      │
│  태스크 L (Low)   : ──► [뮤텍스 획득] ── 선점당함 ─────────►│
│                                                             │
│  [ 우선순위 상속(PIP) 적용 해결 ]                            │
│  태스크 H (High)  :         ───► [뮤텍스 대기] ───► [즉시 실행]│
│  태스크 M (Medium):                  (선점 불가! 대기)      │
│  태스크 L (Low)   : ──► [뮤텍스 획득] ── [우선순위 H로 승격]──┘│
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 저순위 태스크 L이 뮤텍스를 쥐었을 때 우선순위를 H로 일시 승격(PIP)시켜 M의 선점을 막고 빠르게 반납하게 함

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 컨트롤러 (NVIC/GIC) | 하드웨어 신호 우선순위 판별 및 CPU 코어로 IRQ 벡터 신호 전달 |
| Top-Half 핸들러 (Fast ISR) | 인터럽트 즉각 확인(ACK) 및 최소 데이터 레지스터 읽기 후 즉시 복귀 |
| 지연 처리 작업 (Deferred Handler) | 긴 후속 처리를 태스크·스레드 문맥으로 위임해 ISR 실행시간 단축 |
| 우선순위 상속 뮤텍스 (PIP) | 자원을 점유한 저순위 태스크의 우선순위 일시 승격을 통한 중간 태스크 선점 차단 |
| 우선순위 천장 뮤텍스 (PCP) | 자원별 천장 우선순위와 획득 규칙으로 블로킹·교착을 제한 |

#### 한줄 요약
- 인터럽트 컨트롤러, Top/Bottom 분리 핸들러, PIP/PCP 뮤텍스가 하드웨어와 소프트웨어 양단에서 지연을 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 구역(Critical Section)**: 공유 자원의 무결성을 위해 한 번에 하나의 태스크만 접근해야 하는 코드 영역.

</details>

```text
공유 자원 접근 및 인터럽트 발생
      │
      ▼
1. 자원 획득
      │
      ▼
2. 고순위 블로킹
      │
      ▼
3. 우선순위 승격
      │
      ▼
4. 선점 방어
      │
      ▼
5. 정상 스케줄링 복귀
```

**동작 원리**

1. **자원 획득**: 저순위 태스크 L이 임계 구역에 진입해 뮤텍스 락을 획득
2. **고순위 블로킹**: 고순위 태스크 H가 실행 중 해당 자원을 요청하여 대기 상태로 전환
3. **우선순위 승격**: RTOS 커널이 감지하여 태스크 L의 우선순위를 태스크 H와 동일하게 동적 상향
4. **선점 방어**: 중간 순위 태스크 M이 끼어들지 못하도록 방어하고 태스크 L이 임계 구역을 고속 완수
5. **정상 스케줄링 복귀**: 태스크 L이 락을 해제하는 즉시 우선순위가 복원되고 태스크 H가 선점 실행

#### 한줄 요약
- 저순위 락 획득 → 고순위 블로킹 → 우선순위 즉시 승격(PIP) → 선점 방어 및 락 해제 → 고순위 정상 실행 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 실시간 응답 지연 요인 | 인터럽트 레이턴시 | 비제한적 우선순위 역전 | 우선순위 상속 (PIP) | 우선순위 천장 (PCP) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 하드웨어 이벤트 즉각 수신 단계 | 단순 뮤텍스 사용 임베디드 시스템 | 다중 스레드 공유 자원 경합 완화 | 엄격한 다중 락 교착상태 방지 시스템 |
| 핵심 특징 | 하드웨어 인터럽트 진입 지연시간 | 중간 태스크의 무한 선점으로 지연 폭증 | 락을 쥔 저순위 태스크 우선순위 임시 승격 | 락 획득 시 Ceiling 우선순위 즉각 부여 |
| 한계 | 인터럽트 비활성화 구간에 종속 | 화성 탐사선(Mars Pathfinder) 마비 사고 유발 | 다중 자원 시 연쇄 블로킹 및 데드락 가능 | 구현 복잡도 및 과도한 락 상한 오버헤드 |

#### 한줄 요약
- 하드웨어 지연은 인터럽트 레이턴시, 소프트웨어 버그는 우선순위 역전이며, 이를 해결하는 것이 PIP와 PCP다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **화성 패스파인더 사건(Mars Pathfinder Incident)**: 1997년 화성 탐사선에서 정보 버스 뮤텍스 경합으로 비제한적 우선순위 역전이 발생해 시스템 리셋이 반복되었던 사건.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 ISR로 인한 **후속 인터럽트 응답 지연** | 최소 ACK·데이터 포착 후 나머지를 지연 처리로 위임 | 인터럽트 마스킹과 ISR 점유시간 감소 |
| 임계 구역 I/O에 따른 **비제한적 우선순위 역전** | 공유 자원별 PIP 뮤텍스와 임계구역 상한 적용 | 자원 보유 태스크의 중간 우선순위 선점 방지 |
| 중첩 락 순서 불일치에 따른 **교착상태** | PCP 또는 일관된 락 순서와 정적 분석 적용 | 순환 대기와 연쇄 블로킹 위험 제한 |
| 전역 인터럽트 비활성화(CLI/Disable IRQ) 남용 | **세분화된 스핀락(Fine-grained Lock)** 및 락 프리 큐(Lock-Free) 적용 | 시스템 무반응 구간 극소화 |

#### 한줄 요약
- Top/Bottom 분리로 레이턴시를 줄이고, 우선순위 상속으로 역전을 막으며, PCP로 데드락을 원천 차단한다.

## Ⅶ. 결론

- 마감시간에 ISR 지연이 지배하면 **지연 처리**, 공유 락 블로킹이 지배하면 PIP·PCP 선택
- 모든 락에 일괄 적용하지 말고 인터럽트 마스킹·임계구역·중첩 락의 최악 상한을 함께 분석

#### 한줄 요약
- 하드웨어 인터럽트 비활성화 시간을 극소화하고 RTOS 우선순위 상속 프로토콜을 의무화하여 미션 크리티컬 시스템의 안정성을 보장해야 한다.
