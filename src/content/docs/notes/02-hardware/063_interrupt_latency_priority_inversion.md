## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 레이턴시(Interrupt Latency)**: 외부 하드웨어 인터럽트 신호가 인가된 시점부터 CPU가 해당 인터럽트 서비스 루틴(ISR)의 첫 번째 명령어를 실행하기 시작할 때까지 소요되는 지연시간.
- **우선순위 역전(Priority Inversion)**: 저순위 태스크가 보유한 자원을 고순위 태스크가 기다리는 동안 중간 태스크가 선점해 블로킹이 연장되는 현상.

</details>

- 정의/개념: 실시간 시스템의 결정론적 응답성을 저해하는 양대 병목인 **인터럽트 레이턴시**와 공유 자원 동기화 결함인 **우선순위 역전**
- 배경/필요성: 하드웨어 인터럽트 마스킹 및 공유 자원 락(Lock) 경합으로 인한 **비제한적 지연(Unbounded Latency)과 시스템 락업 위험**

#### 한줄 요약
- 인터럽트 지연은 하드웨어와 ISR 진입 시간의 문제이며, 우선순위 역전은 공유 자원 동기화 프로토콜 부재에서 오는 스케줄링 결함이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우선순위 상속 프로토콜(Priority Inheritance Protocol, PIP)**: 공유 뮤텍스를 점유한 저순위 태스크의 우선순위를 해당 자원을 기다리는 최고 우선순위 태스크 수준으로 임시 승격시키는 기법.
- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 자원별 천장 우선순위로 블로킹을 제한하고 교착 조건을 통제하는 기법.

</details>

- 인터럽트 지연시간 구성: 하드웨어 인터럽트 동기화 지연, 전역 인터럽트 마스킹 구간, 레지스터 문맥 저장 시간의 합산으로 결정
- 비제한적 우선순위 역전: 중간 순위 태스크들의 연쇄 선점으로 최악 응답 시간(WCRT) 무한정 증가 위험
- 표준 통제 메커니즘: 인터럽트 지연은 ISR 상·하반부 분리로 단축하고, 우선순위 역전은 **PIP**/PCP 프로토콜로 상한 보장

#### 한줄 요약
- 인터럽트 분리 처리로 응답성을 확보하고, 우선순위 상속/천장 프로토콜로 블로킹 시간 상한을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Top-Half / Bottom-Half 핸들러**: 인터럽트 직후 즉각 처리해야 하는 최소 하드웨어 작업(Top-Half)과 태스크 문맥에서 지연 실행 가능한 본 작업(Bottom-Half)으로 역할을 이원화하는 구조.

</details>

```text
[인터럽트 지연 및 우선순위 역전 통제 체계]
  │
  ├─ [인터럽트 지연 단축 경로] (ISR 이원화)
  │     ├─ [인터럽트 컨트롤러] (NVIC/GIC 신호 감지)
  │     ├─ [Top-Half 빠른 핸들러] (ACK 및 최소 래치)
  │     └─ [Bottom-Half 지연 워커] (태스크 문맥 본처리)
  │
  └─ [우선순위 역전 방어 경로] (동기화 프로토콜)
        ├─ [공유 자원 뮤텍스] (PIP/PCP 적용)
        ├─ [PIP 상속 메커니즘] (저순위 우선순위 승격)
        └─ [PCP 천장 메커니즘] (사전 정의 천장 블로킹 통제)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 컨트롤러 | 우선순위 판정과 인터럽트 벡터 전달 |
| Top-Half ISR | 장치 확인 후 지연 작업 위임 |
| Bottom-Half 워커 | 태스크 문맥에서 후속 처리 수행 |
| PIP 뮤텍스 | 보유 태스크의 우선순위 상속 |
| PCP 뮤텍스 | 천장 우선순위로 블로킹 상한 통제 |

#### 한줄 요약
- 인터럽트 지연은 Top/Bottom-Half 분리로 해결하고, 우선순위 역전은 PIP/PCP 프로토콜을 통해 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **화성 패스파인더(Mars Pathfinder) 사고**: 1997년 화성 탐사선에서 공유 정보 버스 뮤텍스 경합 중 중간 순위 통신 태스크의 선점으로 우선순위 역전이 발생해 시스템 리셋이 무한 반복되었던 대표적 사건.

</details>

```text
[저순위 태스크(Task Low)가 공유 자원 뮤텍스를 획득하여 실행 중]
                               │
                               ▼
1. 고순위 태스크(Task High)가 동일 공유 자원을 요청하며 블로킹(대기) 발생
                               │
                               ▼
2. 동기화 프로토콜 적용 여부 판정
    ┌──────────────────────────┴──────────────────────────┐
 [ 일반 뮤텍스 (방지 기제 없음) ]            [ 우선순위 상속 프로토콜 (PIP 적용) ]
    │                                                     │
    ▼                                                     ▼
3. 무관한 중간 태스크(Task Mid)가            3. Task Low의 우선순위가
   Task Low를 선점(Preemption) 단행              Task High 수준으로 즉각 승격
    │                                                     │
    ▼                                                     ▼
4. 비제한적 우선순위 역전 발생               4. Task Mid가 Task Low를 선점하지
   (Task High 마감시간 초과 및 시스템 락업)      못하도록 완벽 차단
    │                                                     │
    │                                                     ▼
    │                                            Task Low의 임계 구역 신속 완수 및 락 해제
    │                                                     │
    │                                                     ▼
    │                                            Task Low 우선순위 원복 및 Task High 선점 실행
    │                                                     │
    └──────────────────────────┬──────────────────────────┘
                               │
                               ▼
5. 고순위 태스크의 결정론적 마감시간 내 제어 연산 완수
```

- 분기 결과: **PIP** 미적용 시 중간 태스크의 연쇄 선점으로 고순위 태스크가 무기한 블로킹되나, PIP 적용 시 신속히 자원을 해제하여 마감시간을 준수함

**동작 원리**

1. 저순위 태스크(Task Low)의 공유 자원 뮤텍스 점유 임계 구역 실행 중 고순위 태스크(Task High) 활성화 및 자원 요청에 따른 블로킹 전이
2. 커널 스케줄러의 뮤텍스 대기 큐 검사 및 우선순위 상속(PIP) 프로토콜 활성화 여부 판정
3. 비보호 환경 시 자원 무관 중간 태스크(Task Mid) 개입 및 Task Low 선점을 통한 비제한적 우선순위 역전 발생
4. PIP 적용 시 대기 중인 Task High 우선순위로 Task Low의 즉각적 동적 승격 및 Task Mid 선점 원천 차단
5. 임계 구역 신속 완수 및 뮤텍스 반환 후 원래 우선순위 환원 및 Task High로의 즉각적 자원 인계 및 실행 재개

#### 한줄 요약
- 락 경합 ➔ PIP 우선순위 승격 ➔ 중간 태스크 선점 차단 ➔ 신속한 락 해제 ➔ 고순위 태스크 실행 재개의 흐름으로 동작한다.

## Ⅴ. 종류 및 비교

| 대상 구분 | 비제한적 우선순위 역전 (Unbounded) | 우선순위 상속 (Priority Inheritance, PIP) | 우선순위 천장 (Priority Ceiling, PCP) |
|:---|:---|:---|:---|
| 적용 기준 | 단일 태스크 단독 점유 또는 자원 경합이 전무한 비실시간 환경 시 | 단일 공유 자원 상호 배제 및 동적 우선순위 승격만 요구되는 임베디드 환경 시 | 다중 공유 자원 간 데드락 및 연쇄 블로킹 원천 차단 필수인 고신뢰성 제어 시 |
| 핵심 특징 | 기본 우선순위 고정 유지, 무관한 중간 태스크의 무제한 선점 허용, 동기화 오버헤드 전무 | 자원 요청 고순위 태스크 수준으로 동적 우선순위 승격, 중간 태스크 가로채기 차단, 단일 자원 신속 해제 | 공유 자원별 정의된 Ceiling 우선순위 즉각 승격, 상호 대기 교착(Deadlock) 및 연쇄 블로킹 원천 배제 |
| 한계 | 고순위 태스크 무기한 대기 발생 및 시스템 마감시간 초과로 인한 락업 초래 | 다중 자원 중첩 점유 시 연쇄 블로킹 발생 가능 및 교착상태 원천 방지 불가 | 자원별 우선순위 천장값 정적 사전 분석 필수 및 커널 런타임 검사 복잡도 상승 |

#### 한줄 요약
- 동적 상속(PIP)은 간편하게 중간 선점을 막으며, 정적 천장(PCP)은 연쇄 블로킹과 데드락까지 원천 배제한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **락-프리(Lock-Free) 큐**: 뮤텍스 락 없이 원자적 하드웨어 명령어(Compare-And-Swap, CAS)를 활용하여 스레드 간 데이터를 교환하는 비차단 동기화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 ISR로 인한 전역 인터럽트 지연 | **Top-Half/Bottom-Half 구조**로 분리 | 인터럽트 비활성화 시간 단축 |
| 임계 구역 내 I/O 호출에 따른 지연 | **임계 구역 내 I/O 금지** 및 순수 메모리 복사로 제한 | 블로킹 시간 상한을 마이크로초 단위로 극소화 |
| 다중 뮤텍스 사용 시 연쇄 블로킹 | **PCP** 적용 | 교착 방지와 WCRT 상한 분석 |
| 잦은 락 경합에 따른 문맥 교환 오버헤드 | **락-프리 링버퍼** 도입 | 락 대기와 문맥 교환 감소 |

#### 한줄 요약
- 실무에서는 ISR 분리로 인터럽트 지연을 줄이고, PCP와 임계 구역 최소화로 역전을 잡으며, 락-프리 큐로 락 자체를 없앤다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **비교 및 교환(Compare-And-Swap, CAS)**: 메모리 위치의 내용을 기댓값과 원자적으로 비교하여 일치할 때만 새로운 값으로 갱신하는 하드웨어 원자 명령어.
- **읽기-복사-업데이트(Read-Copy-Update, RCU)**: 읽기 작업은 락 없이 수행하고 쓰기 작업은 복사본 수정 후 원자적 포인터 교체로 동기화하는 무잠금 메커니즘.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 인터럽트 지연과 락 블로킹을 포함하여 태스크가 완료되기까지 소요되는 이론적 최대 시간.

</details>

- 전통적 ISR 상·하반부 분리 및 우선순위 상속(PIP/PCP) 프로토콜 기반 통제 체계에서, 멀티코어 확장성 확보를 위한 하드웨어 비교 및 교환(CAS) 기반 락-프리 큐 및 RCU 무잠금 동기화 구조로의 진화 추세.
- 임계 구역 내 I/O 호출 원천 배제와 전역 인터럽트 마스킹 시간 최소화를 수립하고, 최악 응답 시간(WCRT) 상한을 수학적으로 사전 증명하는 결정론적 타이밍 거버넌스 확보 필요.

#### 한줄 요약
- 락-프리 원자 연산 및 RCU 기반 지연 단축과 WCRT 수학적 상한 검증을 융합하여 인터럽트 지연과 우선순위 역전을 통제해야 한다.
