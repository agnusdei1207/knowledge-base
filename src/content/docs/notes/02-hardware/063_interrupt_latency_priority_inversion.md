## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 레이턴시(Interrupt Latency)**: 외부 하드웨어 인터럽트 신호가 인가된 시점부터 CPU가 해당 인터럽트 서비스 루틴(ISR)의 첫 번째 명령어를 실행하기 시작할 때까지 소요되는 지연시간.
- **우선순위 역전(Priority Inversion)**: 고순위 태스크가 저순위 태스크가 점유한 공유 자원(뮤텍스)을 기다리는 동안, 중간 순위 태스크가 CPU를 선점하여 실행됨으로써 고순위 태스크가 무한정 블로킹되는 스케줄링 결함 현상.

</details>

- 정의/개념: 실시간 시스템의 결정론적 응답성을 저해하는 양대 병목인 **인터럽트 레이턴시**와 공유 자원 동기화 결함인 **우선순위 역전**
- 배경/필요성: 단순 연산 가속 의존 → 인터럽트 마스킹과 락 경합 발생 → **실시간 마감시간** 보장 불가 및 시스템 다운 초래

#### 한줄 요약
- 인터럽트 지연은 하드웨어와 ISR 진입 시간의 문제이며, 우선순위 역전은 공유 자원 동기화 프로토콜 부재에서 오는 스케줄링 결함이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **우선순위 상속 프로토콜(Priority Inheritance Protocol, PIP)**: 공유 뮤텍스를 점유한 저순위 태스크의 우선순위를 해당 자원을 기다리는 최고 우선순위 태스크 수준으로 임시 승격시키는 기법.
- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 각 뮤텍스에 접근 가능한 최고 태스크의 우선순위를 Ceiling으로 정적 지정하여 다중 락 시 연쇄 블로킹과 데드락을 원천 방지하는 기법.

</details>

- 인터럽트 지연시간 구성: 하드웨어 인터럽트 동기화 지연, 전역 인터럽트 마스킹 구간, 레지스터 문맥 저장 시간의 합산으로 결정
- 비제한적 우선순위 역전: 중간 순위 태스크들의 연쇄 선점으로 **최악 응답 시간(WCRT)** 무한정 증가 위험
- 표준 통제 메커니즘: 인터럽트 지연은 **ISR 상·하반부 분리**로 단축하고, 우선순위 역전은 **PIP/PCP 프로토콜**로 상한 보장

#### 한줄 요약
- 인터럽트 분리 처리로 응답성을 확보하고, 우선순위 상속/천장 프로토콜로 블로킹 시간 상한을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Top-Half / Bottom-Half 핸들러**: 인터럽트 직후 즉각 처리해야 하는 최소 하드웨어 작업(Top-Half)과 태스크 문맥에서 지연 실행 가능한 본 작업(Bottom-Half)으로 역할을 이원화하는 구조.

</details>

```text
[실시간 지연 및 우선순위 역전 통제 아키텍처]
 ├─ 인터럽트 처리 경로
 │   ├─ 인터럽트 컨트롤러 ──── 우선순위 판별 및 벡터 전달
 │   ├─ Top-Half ISR ────────── 하드웨어 ACK 및 데이터 래치
 │   └─ Bottom-Half 워커 ────── 메시지 큐 및 지연 연산 태스크
 └─ 공유 자원 동기화 경로
     ├─ 우선순위 상속 뮤텍스 ── 저순위 태스크 우선순위 동적 승격
     └─ 우선순위 천장 뮤텍스 ── 자원 획득 시 Ceiling 부여 및 데드락 방지
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어/커널 소속 및 포함 관계; Top-Half가 인터럽트 지연을 줄이고, PIP/PCP가 뮤텍스 역전을 방지함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| 인터럽트 컨트롤러 | MCU 하드웨어 | 다중 인터럽트 우선순위 판별 및 CPU 코어로 인터럽트 벡터 전달 | 하드웨어 벡터링 |
| Top-Half ISR | 커널 인터럽트단 | 최소한의 하드웨어 플래그 클리어 및 래치 후 즉시 인터럽트 복구 | 마이크로초 단위 처리 |
| Bottom-Half 워커 | 스케줄러 태스크단 | 대용량 데이터 파싱 및 복잡한 제어 연산을 태스크 문맥에서 수행 | 선점 가능 실행 |
| 우선순위 상속 (PIP) | RTOS 뮤텍스 엔진 | 락을 쥔 저순위 태스크를 고순위로 동적 승격하여 중간 태스크 선점 차단 | 동적 승격 |
| 우선순위 천장 (PCP) | RTOS 뮤텍스 엔진 | 뮤텍스별 정적 Ceiling 부여로 **연쇄 블로킹** 1회 제한 및 데드락 0화 | 정적 상한 보장 |

#### 한줄 요약
- 인터럽트 지연은 Top/Bottom-Half 분리로 해결하고, 우선순위 역전은 PIP/PCP 프로토콜을 통해 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **화성 패스파인더(Mars Pathfinder) 사고**: 1997년 화성 탐사선에서 공유 정보 버스 뮤텍스 경합 중 중간 순위 통신 태스크의 선점으로 우선순위 역전이 발생해 시스템 리셋이 무한 반복되었던 대표적 사건.

</details>

```text
태스크 실행 중 자원 요청
  │
  ▼
1. 저순위 태스크(Task Low)가 공유 자원(Mutex)을 획득하고 임계 구역 진입
  │
  ▼
2. 고순위 태스크(Task High)가 깨어나 동일한 공유 자원을 요청 (블로킹 발생)
  │
  ▼
3. RTOS의 우선순위 역전 방지 프로토콜 가동 여부
   ┌──────────────────┴──────────────────┐
[ 일반 뮤텍스 (방지 기제 없음) ]       [ 우선순위 상속 프로토콜 (PIP 적용) ]
   │                                     │
   ▼                                     ▼
4. 중간 순위 태스크(Task Mid)가         4. Task Low의 우선순위를 Task High 수준으로 즉시 승격
   Task Low를 선점(Preempt)              │
   │                                     ▼
   ▼                                  5. Task Mid가 Task Low를 선점하지 못하도록 차단
5. Task High가 Task Mid 완료 시까지      │
   무한정 대기 (비제한적 역전)           ▼
   │                                  6. Task Low가 임계 구역 완수 후 Mutex 락 해제
   │                                     │
   ▼                                     ▼
시스템 다운 및 리셋 발생 ◀───────────────┴─ Task Low 우선순위 원복 및 Task High 실행
```

분기 결과: **PIP가 적용되면** 저순위 태스크가 즉시 승격되어 중간 태스크의 가로채기를 차단하므로 고순위 태스크가 마감시간 내에 완수됨

#### 한줄 요약
- 락 경합 ➔ PIP 우선순위 승격 ➔ 중간 태스크 선점 차단 ➔ 신속한 락 해제 ➔ 고순위 태스크 실행 재개의 흐름으로 동작한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 비제한적 우선순위 역전 (Unbounded) | 우선순위 상속 (Priority Inheritance, PIP) | 우선순위 천장 (Priority Ceiling, PCP) |
|:---|:---|:---|:---|
| 우선순위 변경 방식 | 변경 없음 (기본 우선순위 유지) | **자원 요청 고순위 태스크** 수준 동적 승격 | **사전 정의된 Ceiling** 수준 즉시 승격 |
| 중간 태스크 선점 방지 | 불가 (중간 태스크가 계속 가로챔) | **승격된 우선순위**로 선점 완벽 차단 | **Ceiling 우선순위**로 선점 완벽 차단 |
| 연쇄 블로킹 | 무제한 발생 가능 | 다중 자원 시 연쇄 블로킹 가능 | **최대 1개 임계 구역**으로 엄격 제한 |
| 교착상태 (Deadlock) | 발생 위험 높음 | 발생 위험 존재 (상호 대기 락) | **하드웨어/소프트웨어 데드락** 원천 배제 |
| 구현 복잡도 | 최저 | 중간 | 높음 (정적 시스템 사전 분석 필요) |

#### 한줄 요약
- 동적 상속(PIP)은 간편하게 중간 선점을 막으며, 정적 천장(PCP)은 연쇄 블로킹과 데드락까지 원천 배제한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **락-프리(Lock-Free) 큐**: 뮤텍스 락 없이 원자적 하드웨어 명령어(Compare-And-Swap, CAS)를 활용하여 스레드 간 데이터를 교환하는 비차단 동기화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 ISR로 인한 전역 인터럽트 지연 | **Top-Half/Bottom-Half 구조**로 분리 | 전역 인터럽트 비활성화 시간 90% 이상 단축 |
| 임계 구역 내 I/O 호출에 따른 지연 | **임계 구역 내 I/O 금지** 및 순수 메모리 복사로 제한 | 블로킹 시간 상한을 마이크로초 단위로 극소화 |
| 다중 뮤텍스 사용 시 연쇄 블로킹 | **우선순위 천장 프로토콜(PCP)** 적용 | 데드락 0화 및 최악 응답 시간(WCRT) 사수 |
| 잦은 락 경합에 따른 문맥 교환 오버헤드 | **락-프리(Lock-Free) 링버퍼** 도입 | 락 자체를 제거하여 무지연 통신 달성 |

#### 한줄 요약
- 실무에서는 ISR 분리로 인터럽트 지연을 줄이고, PCP와 임계 구역 최소화로 역전을 잡으며, 락-프리 큐로 락 자체를 없앤다.

## Ⅶ. 결론

- **실시간 응답성** 요구 시 ISR 상·하반부 분리와 **PIP·PCP 동기화** 프로토콜 채택

#### 한줄 요약
- 실시간 제어의 신뢰성은 짧은 인터럽트 마스킹과 수학적으로 증명된 동기화 프로토콜(PIP/PCP)의 결합으로 완성된다.
