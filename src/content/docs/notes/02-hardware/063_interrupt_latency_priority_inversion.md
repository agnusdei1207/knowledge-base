## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 레이턴시(Interrupt Latency)**: 하드웨어 인터럽트 요청(IRQ)이 발생한 시점부터 해당 인터럽트 서비스 루틴(ISR)의 첫 번째 명령어가 실행되기까지의 시간.
- **우선순위 역전(Priority Inversion)**: 고우선순위 태스크가 공유 자원(Mutex)을 획득하지 못해 대기하는 동안, 자원을 쥐고 있는 저우선순위 태스크가 중간 우선순위 태스크에 선점당해 고우선순위 태스크가 무기한 지연되는 현상.

</details>

- 정의/개념: 하드웨어 신호 인입부터 ISR 첫 명령어 실행까지 발생하는 하드웨어적 인터럽트 레이턴시(Interrupt Latency)와, 공유 자원 락 경합으로 인해 고우선순위 태스크가 저우선순위에 차단되는 소프트웨어적 우선순위 역전(Priority Inversion)의 원인 및 통합 통제 체계
- 배경/필요성: 인터럽트 지연과 뮤텍스 블로킹이 중첩될 때 발생하는 **실시간 마감시간(Deadline) 위반 및 시스템 락업(화성 패스파인더 호 사태)을 방지하고 결정론적 응답시간 확보**

#### 한줄 요약

- 하드웨어 지연(Interrupt Latency)과 소프트웨어 지연(우선순위 역전)의 **원인 분리 및 결정론적 WCRT 통제**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Interrupt Masking(인터럽트 마스킹)**: 원자적 연산 수행을 위해 CPU의 인터럽트 활성화 플래그를 비활성화(CLI)하여 외부 IRQ를 차단하는 구간.
- **Unbounded Priority Inversion(무한 우선순위 역전)**: 중간 우선순위 태스크들이 계속 끼어들어 저우선순위 태스크의 자원 반납을 지연시킴으로써 고우선순위 태스크가 예측할 수 없는 시간 동안 멈추는 상태.

</details>

- 하드웨어 인터럽트 비활성화(마스킹) 구간 및 레지스터 문맥 보존(Context Save)에 따른 **물리적 인터럽트 지연 유발**
- 공유 자원 잠금 상태에서 중간 우선순위 태스크의 간섭으로 발생하는 **무한 우선순위 역전(Unbounded Inversion)** 방지 필수
- 실시간 마감시간 엄수를 위해 하드웨어 레이턴시와 소프트웨어 락 차단 시간을 합산한 **최악 응답 시간(WCRT) 상한 통제**

#### 한줄 요약

- **인터럽트 마스킹/문맥 보존 지연·중간 우선순위 선점 차단(Unbounded Inversion)·WCRT 수학적 상한 제어**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Interrupt Controller(NVIC/GIC)**: 하드웨어 핀 인터럽트 우선순위를 중재하고 CPU에 신호를 전달하는 하드웨어 유닛.
- **Priority Ceiling Protocol(PCP)**: 공유 뮤텍스마다 정의된 우선순위 천장 값을 통해 데드락과 다중 블로킹을 원천 방지하는 프로토콜.

</details>

```text
[ 실시간 지연 요소 및 통제 계층 구조도 ]
┌──────────────────────────────┐        ┌──────────────────────────────┐
│ 하드웨어 지연 계층           │        │ 소프트웨어 커널 지연 계층     │
│  [ 인터럽트 컨트롤러 (NVIC) ] │        │  [ RTOS 선점형 스케줄러 ]    │
│            │ (IRQ)           │        │            │ (선점 제어)     │
│            ▼                 │        │            ▼                 │
│  [ 하드웨어 문맥 저장 / ISR ] │        │  [ 공유 자원 Mutex (PIP/PCP)] │
│  (인터럽트 레이턴시 발생 지점)│        │  (우선순위 역전 발생 지점)   │
└──────────────────────────────┘        └──────────────────────────────┘
```

선의 의미: 인터럽트 컨트롤러(NVIC/GIC), 예외 진입 및 ISR, 실시간 스케줄러, 임계 구역 및 뮤텍스 락 간의 지연 제어 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 컨트롤러 | 센서 핀에 불이 들어오면 우선순위를 따져보고 CPU 멱살을 잡아채는 하드웨어 문지기 |
| 예외 진입 및 ISR | 하던 일의 뇌 상태(레지스터)를 스택에 냅다 던져버리고 특수부대(ISR)를 투입하는 하드웨어 래칭 |
| 실시간 스케줄러 | 어떤 놈이 우선순위 새치기를 당하는지 째려보다가 권력을 휘둘러 순서를 바로잡는 재판관 |
| 임계 구역 뮤텍스 락 | 두 놈이 동시에 건드리면 데이터가 박살 나는 **임계 구역**을 방어하기 위해 문을 걸어 잠그는 자물쇠 |

#### 한줄 요약

- **인터럽트 컨트롤러·예외 진입/ISR(Top-Half)·RTOS 선점 스케줄러·임계 구역 뮤텍스(PIP/PCP)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Priority Inheritance Protocol(PIP)**: 공유 자원을 선점 중인 저우선순위 태스크에게 대기 중인 최고 우선순위 태스크의 우선순위를 일시적으로 상속하여 중우선순위 태스크의 선점을 방지하는 메커니즘.

</details>

```text
[ 인터럽트 지연 및 우선순위 상속(PIP) 처리 시퀀스 ]
 
 [ 1. 하드웨어 인터럽트 레이턴시 경로 ]
   [ 외부 센서 IRQ 핀 트리거 ] ──> [ 인터럽트 마스킹 해제 대기 ] ──> [ CPU 레지스터 스택 덤프 ] ──> [ ISR 핸들러 첫 줄 실행 ]
 
 [ 2. 소프트웨어 우선순위 역전 해결 경로 (Priority Inheritance) ]
   [ 고우선순위 태스크 H 가 자원 R 요청 ]
                     │
                     ▼
   [ 저우선순위 태스크 L 이 자원 R 점유 중 감지 ]
                     │
                     ▼
   [ 태스크 L 의 우선순위를 태스크 H 로 즉시 임시 승격 (PIP 발동) ]
                     │ (중우선순위 태스크 M 의 선점 차단!)
                     ▼
   [ 태스크 L 이 빠르게 자원 R 반납 및 원래 우선순위로 복귀 ]
                     │
                     ▼
   [ 태스크 H 가 자원 R 획득 후 즉시 고속 연산 완료 ]
```

**동작 원리**

1. **인터럽트 마스킹 대기**: CPU가 임계 구역을 빠져나와 인터럽트를 허용할 때까지 하드웨어 지연 발생
2. **ISR 진입**: CPU 파이프라인 플러시 및 하드웨어 문맥 저장을 거쳐 인터럽트 벡터 핸들러 진입
3. **자원 경합 식별**: 고우선순위 태스크 H가 저우선순위 태스크 L이 잠근 뮤텍스를 요청하여 블로킹 발생
4. **우선순위 상속(PIP)**: 커널이 태스크 L의 우선순위를 태스크 H와 동일하게 승격하여 태스크 M의 선점 차단
5. **자원 해제 및 복귀**: 태스크 L이 임계 구역을 벗어나 락을 해제하는 즉시 우선순위 원복 및 태스크 H 실행

#### 한줄 요약

- IRQ 발생 $\to$ **마스킹 해제 & ISR 진입(레이턴시) $\to$ 뮤텍스 경합 발생 $\to$ 저우선순위에 우선순위 상속(PIP) $\to$ 자원 조기 해제 및 고우선순위 실행**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인터럽트 레이턴시 vs 우선순위 역전 비교**:
  - 인터럽트 레이턴시: HW 인터럽트 $\to$ ISR 진입 지연, Top/Bottom-Half 분리로 완화
  - 우선순위 역전: SW 뮤텍스 락 경합으로 인한 지연, PIP/PCP 프로토콜로 해결

</details>

| 비교 항목 | 인터럽트 레이턴시 (Hardware/Driver 레벨) | 우선순위 역전 (RTOS Kernel/Mutex 레벨) |
|:---|:---|:---|
| 관측 구간 및 정의 | IRQ 핀 신호 발생 $\to$ ISR 핸들러 첫 코드 실행 시점 | 고우선순위 태스크가 저우선순위 보유 락으로 인해 차단된 시간 |
| 주 발생 원인 | 인터럽트 비활성화(마스킹) 구간, HW 파이프라인/문맥 보존 | 공유 자원(Mutex) 미세 선점 중 제3의 중우선순위 태스크 개입 |
| 해결 대책 및 프로토콜 | 인터럽트 마스킹 시간 최소화, Top/Bottom-Half 분리 처리 | 우선순위 상속(PIP), 우선순위 상한(PCP) 프로토콜 적용 |

#### 한줄 요약

- 하드웨어 지연은 **인터럽트 레이턴시(Top-Half 최소화)**, 소프트웨어 락 차단은 **우선순위 역전(PIP/PCP 상속)**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Top-Half / Bottom-Half**: ISR(Top-Half)에서는 하드웨어 플래그만 클리어하고 즉시 복귀한 뒤, 무거운 데이터 처리는 태스크/DPC(Bottom-Half)로 이관하는 설계.
- **IRQ Throttling**: 고주파 인터럽트로 인한 CPU 기아를 방지하기 위해 인터럽트 발생률을 하드웨어 타이머로 조절하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CPU 귀를 너무 오래 닫아둬서(마스킹) 그사이 발생한 에어백 센서 비명을 놓치고 운전자가 뒈지는 대형 참사 | ISR에서는 깃발(플래그)만 꽂고 진짜 빡센 계산은 나중으로 냅다 미루는 **지연 처리**(Bottom-half) 적용 | 어떻게든 **인터럽트 레이턴시**를 극한으로 쥐어짜 줄여서 다음 센서를 절대 놓치지 않고 수용 |
| 메모리를 두고 엉뚱한 놈팽이(중순위)가 새치기하여 장군이 무한 대기 타는 **우선순위 역전** 셧다운 마비 | **우선순위 상속** 프로토콜(PIP) 커널 강제 적용으로 하사관을 미친 듯이 쪼아서 빨리 나가게 만듦 | 억울한 새치기(**중순위 선점**)에 의한 무한 대기 셧다운 사태를 원천 차단하고 통제권 회복 |
| 불필요한 센서가 1초에 수만 번씩 비명을 질러 정작 중요한 태스크가 굶어 죽는 **인터럽트 기아** | 타이머로 인터럽트 빈도에 족쇄(Throttling)를 채우거나, 단순 데이터는 CPU 대신 DMA 칩에 짬 때려버림 | 미친 듯이 튀는 CPU 부하율을 진정시키고 비명 소리에 묻혀 시스템이 마비되는 현상 선제 방어 |

#### 한줄 요약

- **Top/Bottom-Half 지연 처리 분리·Priority Inheritance/Ceiling 프로토콜·IRQ Throttling & DMA 전송**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **화성 패스파인더 호 교훈**: 1997년 화성 착륙선이 우선순위 역전 버그로 반복 리셋된 사건 이후, 모든 항공/우주/자동차 RTOS 커널에서 우선순위 상속(PIP) 옵션 활성화가 필수 표준화됨.

</details>

- 임베디드 실시간 시스템 구축 시 **인터럽트 마스킹을 $\mu\text{s}$ 단위로 극소화하고 모든 공유 뮤텍스에 우선순위 상속(PIP) 표준 채택**

#### 한줄 요약

- **인터럽트 지연과 락 차단 시간의 이중 상한 관리**를 통한 WCRT 준수 보장
