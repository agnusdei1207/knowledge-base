## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 컴퓨터처럼 이것저것 다 하는 게 아니라, 세탁기 모터를 돌리거나 자동차 브레이크를 잡는 딱 '한 가지 목적'만을 위해 칩과 펌웨어를 뼛속까지 결합한 전용 기계이다.
- **펌웨어(Firmware)**: 윈도우처럼 하드디스크에 깔리는 게 아니라, 공장에서 나올 때부터 칩 안의 롬(ROM) 메모리에 문신처럼 새겨져 하드웨어를 직접 멱살 잡고 통제하는 불멸의 코드이다.
- **하드웨어 소프트웨어 분할(HW/SW Partitioning)**: 속도가 생명인 작업은 무식하게 빠른 하드웨어 칩(회로)에 맡기고, 복잡한 계산은 펌웨어(소프트웨어)로 넘기는 설계의 예술이다.

</details>

- 정의: 제한된 전력, 쥐꼬리만 한 메모리, 연산 자원 조건 하에 자동차 엔진 제어 같은 특정 목적만을 독하게 전용 수행하는 **임베디드 시스템**
- 배경: 범용 PC나 서버로는 배터리로 며칠을 버티면서 0.001초 단위의 깐깐한 **제어 마감시간 보장 곤란**의 치명적 한계가 존재했기 때문

#### 한줄 요약

- 배터리로 몇 달을 버티며, 정해진 시간 안에 반드시 에어백을 터뜨리거나 모터를 돌리기 위해 불필요한 기능은 다 뺀 독한 전용 컴퓨터이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 차가 벽에 부딪히면 0.01초 안에 에어백이 터져야 한다는 식의, 단 0.001초라도 늦으면 사람이 죽을 수도 있는 얄짤없는 시간제한이다.
- **실시간 입출력(Real-Time I/O)**: 중간에 운영체제가 "잠깐만요" 하고 딴짓하는 걸 절대 용납하지 않고, 센서가 들어오면 즉각 핀을 쏴버리는 다이렉트 반응이다.
- **제한 자원(Resource Constraints)**: 칩이 크면 비싸고 배터리를 많이 먹으므로, 메모리(RAM)를 킬로바이트(KB) 단위로 아껴 써야 하는 피눈물 나는 짠돌이 환경이다.

</details>

- 에어백 센서가 터지면 무조건 0.01초 안에 가스를 터뜨려야 하는 자비 없는 **마감시간** 엄수성 기능을 가짐.
- 중간에 운영체제(OS)가 딴짓하는 걸 용납하지 않고 센서 핀과 모터 핀을 직접 제어하는 얄짤없는 **실시간 입출력**을 달성함.
- 배터리가 조루가 되지 않게 최소한의 칩셋 면적과 RAM만 쓰는 짠돌이 **제한 자원** 최적화 설계를 강제함.
- 마감시간 전력 변경성에 따른 피 말리는 **하드웨어 소프트웨어 분할** 구조를 채택함.

#### 한줄 요약

- 속도가 1순위(마감시간), 전기를 덜 먹는 게 2순위(제한 자원)이므로, 무거운 운영체제 대신 가벼운 펌웨어가 핀을 직접 제어(실시간 I/O)한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **입력부(Input Unit)**: 아날로그 온도나 압력 센서 신호를 받아, 칩이 알아먹을 수 있는 디지털(0과 1)로 번역해 주는 센서 접수처이다.
- **처리 제어부(Processing & Control Unit)**: 센서 값을 보고 "모터를 얼마나 돌려라!"라고 계산한 뒤, 타이머를 쪼개며 미친 듯이 명령을 내리는 칩의 뇌하수체이다.
- **메모리부(Memory Unit)**: 전원이 꺼져도 코드가 날아가지 않는 플래시 롬(ROM)과, 계산할 때 잠시 변수를 적어두는 램(SRAM)이 합쳐진 작은 저장소이다.
- **통신부(Communication Unit)**: 칩 혼자 놀지 않고 자동차 안의 다른 부품들과 CAN이나 SPI 같은 전용 고속도로를 통해 끊임없이 대화하는 무전기이다.
- **출력 복구부(Output & Recovery Unit)**: 뇌의 명령을 받아 모터나 밸브를 돌리고, 시스템이 뻗으면 강제로 재부팅 버튼을 눌러버리는 물리적 팔다리이다.
- **워치독(Watchdog Timer)**: 펌웨어가 멈춰서 개한테 먹이를 안 주면, 시스템이 죽은 줄 알고 알아서 컴퓨터 전원을 내렸다가 켜버리는 무자비한 타이머이다.

</details>

```text
[ 임베디드 시스템 하드웨어 모듈 및 펌웨어 제어 구조 ]
                         [ 메모리부 (코드 ROM / 변수 RAM) ]
                                   │
[ 외부 센서 입력부 ] ▶ [ 뇌하수체 처리 제어부 (MCU 코어) ] ▶ [ 외부 직렬 통신부 (CAN/SPI) ]
                                   │
                         [ 출력 복구부 (모터 / 워치독 타이머) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 센서 **입력부** | 아날로그 온도/압력 센서 신호를 쑤셔 넣고 0101 디지털(ADC)로 번역함 |
| 뇌하수체 **처리 제어부** | 마이크로컨트롤러(MCU) 코어가 타이머를 쪼개며 실시간 태스크를 멱살 잡고 스케줄링함 |
| **메모리부** | 전원이 꺼져도 절대 안 날아가는 Flash 롬에 펌웨어 코드를 문신처럼 새겨서 저장함 |
| 직렬 **통신부** | 자동차 안의 다른 부품들과 CAN이나 SPI 버스로 끊임없이 데이터를 주고받음 |
| **출력 복구부** | 모터나 밸브를 냅다 돌리고, 펌웨어가 뻗으면 **워치독**이 강제로 재부팅 버튼을 눌러버림 |

#### 한줄 요약

- 센서(입력)의 값을 뇌(제어부)가 읽어 모터(출력)를 돌리며, 만약 뇌가 멈추면 워치독(복구부)이 시스템을 강제로 껐다 켜서 살려낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **제어 주기(Control Cycle)**: 센서를 읽고, 계산하고, 모터를 돌리는 이 3단계 과정을 1초에 수백 번씩 미친 듯이 똑같이 반복하는 무한 루프이다.
- **안전 상태(Safe State)**: 시스템이 고장 났을 때 모터가 폭주해서 사람을 다치게 하지 않도록, 모터 전원을 끊어버리거나 브레이크를 잠가버리는 방어 상태이다.

</details>

```text
[ 펌웨어 무한 루프 센서 획득 및 0.01초 워치독 강제 복구 생존 흐름 ]
                               │
                               ▼
     [ 1. 아날로그 센서 신호를 디지털로 즉각 변환하여 칩으로 쑤셔 넣음 ]
                               │
                               ▼
        [ 2. 뇌하수체 처리 제어부가 알고리즘을 굴려 모터 각도를 냅다 계산 ]
                               │
                               ▼
    [ 3. 차가 처박히기 전(마감시간 내) 모터 제어 신호(PWM)를 하드웨어 핀에 꽂음 ]
                               │
            +---------------------------------------+
            |      [ 0.01초 마감시간 내에 끝났는가? ]   |
            |      /                        \       |
            |   [ 예 ]                   [ 아니요 ] |
            |     │                          │      |
            | 개(워치독)에게 먹이 줌     4. 비상 안전 출력 모드 전환  |
            | (다시 1번으로 무한 반복)   5. 워치독 리셋(강제 재부팅)  |
            +---------------------------------------+
```

### 동작 원리

1. 아날로그 입력 변환 수용: 센서 ADC 변환 및 하드웨어 핀 인터럽트를 통해 외부 자극을 즉각 수용함.
2. 뼈를 깎는 실시간 제어 연산: 뇌하수체인 **처리 제어부**가 알고리즘을 계산하고 액추에이터(모터)를 얼마나 꺾을지 냅다 도출함.
3. 칼 같은 제어 출력 적용: 자동차가 처박히기 전 **마감시간** 내에 모터(PWM) 출력 신호를 하드웨어 핀에 가차 없이 박아넣음.
4. 비상 안전 출력 전환: 마감시간을 놓치거나 펌웨어가 뻗으면, 폭주를 막기 위해 시스템을 멈춰 세우는 **안전 상태** 출력으로 강제 전환함.
5. 워치독 리셋 오류 복구: 개(워치독)가 짖기 전 먹이를 못 주면 시스템 전원을 확 내렸다 켜버리는 강제 재시동을 수행함.

#### 한줄 요약

- 0.01초마다 센서를 읽고 모터를 돌리면서 워치독 타이머를 리셋시켜 주는데, 코드가 뻗어서 리셋을 못 시키면 워치독이 강제로 서버를 껐다 켠다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **엠씨유(Microcontroller Unit)**: CPU 뇌와 메모리, 핀을 새끼손톱만 한 칩 하나에 몽땅 때려 박은 가성비 극강의 칩으로, 밥솥이나 리모컨에 들어간다.
- **엠피유(Microprocessor Unit)**: MCU로는 화면을 띄우거나 와이파이를 잡기 버거우니, 외부 램(DRAM)을 달고 리눅스를 올려 스마트폰이나 블랙박스처럼 쓰는 칩이다.

</details>

| 임베디드 시스템 | **엠씨유** (MCU) 기반 구조 | **엠피유** / SoC (MPU) 기반 구조 |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 밥솥, 전자레인지, 자동차 브레이크처럼 한 가지 일만 죽어라 빠르고 완벽하게 해야 할 시 | 스마트 TV, 블랙박스처럼 화면도 띄우고 와이파이도 잡으며 딴짓(멀티태스킹)도 섞어야 할 시 |
| 아키텍처 핵심 구현 특징 | 칩 하나에 CPU, 램, 롬을 몽땅 때려 박아 100원짜리 동전 크기로 만든 **엠씨유** 극강의 가성비 | 외부 램(DRAM)을 주렁주렁 달고 무거운 리눅스(OS)까지 올려서 PC를 흉내 내는 하이엔드 **엠피유** 구조 |
| 극복해야 할 태생적 한계점 | 칩 안의 램이 코딱지만 해서 덩치 큰 프로그램이나 딥러닝 모델은 꿈도 못 꾸는 치명적 제약 | 전기를 무식하게 퍼먹고 부팅하는 데 한참 걸려, 에어백처럼 0.01초 반응이 생명인 곳엔 절대 못 씀 |

#### 한줄 요약

- 배터리를 아끼고 0.01초 만에 반응해야 하면 싸구려 MCU를 쓰고, 예쁜 화면도 띄우고 통신도 빵빵하게 해야 하면 비싼 MPU를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 펌웨어 코드가 재수 없게 모든 if 문 조건에 다 걸려서 가장 오래 뺑뺑이를 돌았을 때 걸리는 최악의 시간 계산법이다.
- **에이비 파티션(A/B Partitioning)**: 테슬라처럼 차를 무선 업데이트(OTA) 하다가 인터넷이 끊기면 차가 먹통이 되니까, 메모리 방을 두 개로 쪼개 실패하면 예전 코드로 롤백하는 생존 기술이다.
- **에이치아이엘(Hardware-in-the-Loop, HIL)**: 실제 자동차에 보드를 달고 브레이크 테스트를 하다간 연구원이 죽을 수 있으니, 컴퓨터가 가짜 센서 신호를 쏴주며 방구석에서 수만 번 굴려보는 시뮬레이터이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 펌웨어 코드를 발로 짜서 **마감시간**을 놓쳐 브레이크가 안 밟히는 끔찍한 오작동 대참사 | 코드의 **최악 실행 시간**(WCET)을 뼛속까지 분석하여 RTOS 타이머 우선순위를 칼같이 멱살 잡고 재배치 | 어떤 악조건에서도 0.01초 안에 무조건 반응하는 지독한 실시간 결정성 100% 확보 달성 |
| 자동차 펌웨어 무선 업데이트(OTA) 중 인터넷이 끊겨 자동차가 쇳덩이(벽돌)가 되는 끔찍한 셧다운 위험 | 칩 안에 메모리 뱅크를 두 개(A/B)로 쪼개어, 펌웨어 갱신 실패 시 예전 코드로 냅다 롤백(**에이비 파티션**) | 실패한 펌웨어 업데이트 때문에 장비가 먹통이 되는 끔찍한 A/S 사태를 완벽하게 예방 및 복구 |
| 실제 자동차에 보드를 달고 극한 테스트하다가 브레이크가 안 들어 연구원이 벽에 처박히는 사망 위험 | 진짜 센서 대신 컴퓨터로 뻥튀기 신호를 쏴주는 가상 시뮬레이터(**에이치아이엘**) 기반 십자포화 테스트 수행 | 사람이 다치지 않고도 수만 번의 기괴한 고장 주입 테스트를 돌려 안전 출력 및 복구 절차를 완벽 검증 |

#### 한줄 요약

- 코드가 늦게 도는 걸 막고(WCET 최적화), 업데이트 실패 시 옛날 코드로 돌아가며(A/B 파티션), 가짜 신호(HIL)를 쏴서 차가 안 박게 테스트해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **임베디드 처리 구조 선택 기준(Embedded Architecture Selection Criteria)**: 이 기계가 0.01초 안에 반응해야 하는지, 배터리로 1년을 버텨야 하는지, 화려한 그래픽이 필요한지를 따져 칩을 고르는 견적서 잣대이다.

</details>

- **임베디드 처리 구조 선택 기준**에 따라 초저전력 및 얄짤없는 단순 실시간 제어는 **엠씨유**(MCU), OS 및 화려한 그래픽 멀티 처리는 **엠피유**(MPU/SoC) 선정 기조를 확립함

#### 한줄 요약

- 밥솥이나 에어백처럼 빠르고 단순한 놈은 MCU를 꽂고, 내비게이션처럼 복잡하고 화면 띄우는 놈은 MPU를 꽂아라.
