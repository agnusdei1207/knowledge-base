## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 특정 목적의 기능을 전용 수행하기 위해 마이크로프로세서, 메모리 및 I/O 펌웨어를 물리 결합한 시스템.
- **펌웨어(Firmware)**: 임베디드 칩셋의 ROM/Flash 메모리에 상주하여 하드웨어를 직접 제어하는 캡슐화된 제어 로직.
- **하드웨어·소프트웨어 분할(HW/SW Partitioning)**: 시스템 요구 조건에 근거하여 기능을 HW 전용 로직과 SW 펌웨어로 분할 배치하는 설계 기법.

</details>

- 정의/개념: 제한된 전력, 메모리, 연산 자원 조건 하에 특정 제어 및 센서 반응 기능을 전용 수행하는 **임베디드 시스템**
- 배경/필요성: 범용 시스템으로는 제한 전력에서 **제어 마감시간 보장 곤란**

#### 한줄 요약

- 임베디드 시스템은 제한된 자원 안에서 센서 입력을 처리하고 정해진 시간에 제어 출력을 생성하도록 하드웨어와 펌웨어를 결합한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **마감시간(Deadline)**: 센서 신호 유입 후 액추에이터 제어 명령이 반드시 출력 완료되어야 하는 시한 한계.
- **실시간 입출력(Real-Time I/O)**: 센서 인터럽트 인가 시 지연시간 상한(Bounded Latency) 내에 I/O를 제어하는 동작.
- **제한 자원(Resource Constraints)**: 칩셋 면적, ROM/RAM 용량, 소비 전력 및 발열 요구사항에 따른 물리적 제약.

</details>

- 제어 주기의 지연 상한을 보장하는 **마감시간** 엄수성
- 센서 및 액추에이터 인터페이스를 직접 제어하는 **실시간 입출력**
- 최소한의 하드웨어 전력/메모리 부하를 달성하는 **제한 자원** 최적화 설계
- 마감시간·전력·변경성에 따른 **HW/SW 분할**

#### 한줄 요약

- 마감시간·전력·변경 요구를 함께 비교해 기능을 전용 회로 또는 펌웨어로 분할한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **입력부(Input Unit)**: ADC, GPIO, 센서 인터럽트 신호를 수용하는 인터페이스.
- **처리·제어부(Processing & Control Unit)**: MCU/MPU 메인 연산 코어 및 RTOS 커널 스케줄러.
- **메모리부(Memory Unit)**: Flash ROM(펌웨어 보관) 및 SRAM(실행 변수 저장).
- **통신부(Communication Unit)**: CAN, UART, SPI, I2C 등 임베디드 직렬 통신 Bus.
- **출력·복구부(Output & Recovery Unit)**: PWM, DAC, 액추에이터 제어기 및 **워치독(Watchdog Timer)** 기반 장애 복구 장치.

</details>

```text
                         [메모리부]
                              |
[입력부] ----- [처리•제어부] ----- [통신부]
                      |
                [출력•복구부]
```

선의 의미: 처리·제어부를 중앙에 배치하고 입력, 메모리, 통신, 출력/복구 모듈이 결합된 하드웨어 시스템 블록.

| 구성요소 | 책임 |
|:---|:---|
| 입력부 | 아날로그/디지털 센서 신호 수용 및 **ADC** 변환 |
| 처리•제어부 | 코어 연산, 실시간 태스크 스케줄링 및 알고리즘 수행 |
| 메모리부 | Flash/SRAM 기반 펌웨어 코드 및 시스템 컨텍스트 저장 |
| 통신부 | CAN/SPI/I2C 버스 제어 및 외부 오프보드 모듈 전송 |
| 출력•복구부 | 액추에이터 PWM 제어 및 **워치독** 타이머 기반 자동 복구 |

#### 한줄 요약

- 입력부의 센서값을 처리·제어부가 계산해 출력부에 반영하고, 오류 시 워치독과 안전 출력이 위험 동작을 제한한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **제어 주기(Control Cycle)**: 센서 획득-연산-액추에이터 출력까지 정기적으로 반복되는 타임 슬롯.
- **워치독(Watchdog Timer)**: 펌웨어 교착 상태나 Infinite Loop 도달 시 시스템을 강제 리셋시키는 카운터 타이머.
- **안전 상태(Safe State)**: 오작동 시 물리적 위해를 막기 위해 시스템 출력을 차단/정지시키는 보호 레벨.

</details>

```text
 [센서•물리 플랜트]
          |
 1. 입력 변환•상태 조회
          |
 2. 실시간 제어 연산
          |
 3. 제어 출력 적용
          |
    [마감시간 내 완료?]
       ├─ 예
       │  └─ [워치독 갱신 후 제어 주기 반복]
       └─ 아니요•정지
          └─ 4. 안전 출력 전환
             └─ 5. 워치독 리셋·오류 복구
                └─ [제어 주기 재시작]
```

### 동작 원리

1. 입력 변환·상태 조회: 센서 **ADC** 변환 및 GPIO 인터럽트를 통한 실시간 입력 수용.
2. 실시간 제어 연산: **처리**•**제어부**를 통한 알고리즘 계산 및 액추에이터 제어량 도출.
3. 제어 출력 적용: **마감시간** 내 액추에이터 **PWM** 출력 적용.
4. 안전 출력 전환: 마감시간 초과 또는 커널 락업 감지 시 **안전 상태** 출력으로 강제 전환.
5. 워치독 리셋·오류 복구: **워치독** 시스템 리셋 인가 및 정상 부팅 파티션으로 하드웨어 재시동.

#### 한줄 요약

- 제어 주기를 마감시간 안에 끝내면 워치독을 갱신하고, 시간 초과나 정지 시 안전 출력을 적용한 뒤 복구 절차를 실행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MCU(Microcontroller Unit)**: CPU 코어, ROM, RAM, I/O를 단일 실리콘 다이에 집적한 저전력 전용 칩셋.
- **MPU/SoC(Microprocessor Unit / System on Chip)**: 외부 DRAM을 연동하여 고성능 OS(Linux 등) 및 그래픽/네트워크를 제어하는 칩셋.

</details>

| 임베디드 시스템 | MCU 기반 구조 | MPU / SoC 기반 구조 |
|:---|:---|:---|
| 적용 기준 | 초저전력, 콤팩트 제어, 실시간 펌웨어 전용 구동 시 | 멀티태스킹 OS, GUI 디스플레이 및 고속 통신 처리 시 |
| 핵심 특징 | **MCU**의 온칩 Flash/SRAM 및 초저전력 모드 | **MPU**•**SoC**의 외부 DRAM 확장 및 하이엔드 코어 |
| 한계 | 메모리 확장 및 대용량 연산 한계 | 상대적으로 높은 소비 전력 및 칩 단가 상승 |

#### 한줄 요약

- 저전력·단순 실시간 제어에는 MCU가, 화면·네트워크·대용량 메모리가 필요한 고기능 처리에는 MPU·SoC가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **WCET(Worst-Case Execution Time)**: 태스크가 연산 시 유발할 수 있는 가장 긴 이론적 최악 실행 시간.
- **A/B 파티션(A/B Partitioning)**: OTA 펌웨어 업데이트 시 듀얼 뱅크 플래시를 사용하여 업데이트 실패 시 롤백하는 구조.
- **HIL(Hardware-in-the-Loop)**: 제어기 타깃을 실제 차량/장비 모의 시뮬레이터에 연결하여 입출력을 실시간 검증하는 HIL 테스트.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 알고리즘 불확실성으로 인한 **마감시간** 초과 오작동 | static **WCET** 분석 및 RTOS 태스크 우선순위 재배치 | 실시간 결정성 확보 |
| 펌웨어 업데이트 중 정전으로 부팅 불능 위험 | **A/B 파티션** 듀얼 뱅크 갱신 및 롤백 제어 | 실패한 펌웨어 갱신에서 복구 |
| 시스템 무반응 사태 방치 위험 | 독립 **워치독** 타이머 및 HW 세이프가드 수용 | 고장 발생 시 **안전 상태** 전환 |
| 현장 센서·통신 장애 조건의 재현 부족 | **HIL** 기반 장애 주입과 마감시간 측정 | 안전 출력·복구 절차 사전 검증 |

> 사례: **MCU** 기반 **A/B 파티션** 듀얼 뱅크 설계 및 안전 **워치독** 구축

#### 한줄 요약

- HIL 장애 주입으로 마감시간 초과와 통신·센서 오류를 재현해 안전 출력과 워치독 복구 절차를 검증한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **임베디드 처리 구조 선택 기준(Embedded Architecture Selection Criteria)**: 마감시간 실시간성, 타깃 연산 복잡도 및 전력 한계에 기반한 칩셋 선택 체계.

</details>

- **임베디드 처리 구조 선택 기준**에 따라 초저전력 및 단순 실시간 제어는 **MCU**, OS 및 그래픽 처리는 **MPU/SoC** 선정

#### 한줄 요약

- 단순 저전력 제어는 MCU, OS·그래픽 처리는 MPU·SoC를 선택한다.
