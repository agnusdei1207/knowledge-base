## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 특정 목적의 전자기기나 기계 장치 내부에 내장되어 제어, 통신, 센싱을 전담하는 하드웨어·소프트웨어 통합 컴퓨팅 시스템.
- **HW/SW 공동 설계(HW/SW Co-Design)**: 목표 성능, 전력, 비용 요구사항에 맞춰 기능을 하드웨어 회로와 소프트웨어 알고리즘으로 최적 분할하는 설계 방법론.

</details>

- 정의/개념: 특정 전자기기 제어를 위해 마이크로프로세서와 메모리, I/O 주변장치 및 **펌웨어/RTOS 소프트웨어**를 통합한 특화 컴퓨팅 시스템 구조
- 배경/필요성: 범용 컴퓨터 구조의 높은 소비 전력·비용 극복 및 열악한 현장 환경에서의 결정적 실시간 제어 보장 필요

#### 한줄 요약
- 가전, 자동차, 산업 기계 등에 내장되어 정해진 제어 기능을 초저전력·실시간으로 수행하는 전용 컴퓨터 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **실시간성(Real-Time Property)**: 논리적인 연산 결과의 정확성뿐만 아니라 정해진 시간 제약(Deadline) 내에 결과를 출력해야 하는 특성.
- **자원 제약성(Resource Constraint)**: 배터리 수명, 초소형 패키지 면적, 제한된 메모리 용량(KB~MB 단위) 내에서 동작해야 하는 하드웨어 제약.

</details>

- **HW/SW 공동 설계**를 통한 시스템 폼팩터 소형화 및 BOM 단가 극소화
- 이벤트 발생 시 정해진 마감시간(Deadline) 내 처리를 보장하는 **결정적 실시간성**
- 열악한 산업 환경(고온·진동·노이즈)에서의 고신뢰성 및 저전력(Sleep/Wakeup) 운용

#### 한줄 요약
- 작고 가벼운 부품으로 회로를 꾸미고, 전기를 극도로 아끼며, 1초의 오차도 없이 센서와 모터를 제어한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워치독 타이머(Watchdog Timer, WDT)**: 소프트웨어가 무한 루프나 다운 상태에 빠졌을 때 주기적 신호(Kick) 부재를 감지해 시스템을 강제 리셋하는 하드웨어 타이머.
- **액추에이터(Actuator)**: 전기 제어 신호를 모터 회전, 밸브 개폐, 릴레이 동작 등 물리적 운동으로 변환하는 장치.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 임베디드 하드웨어 및 소프트웨어 계층 구조                   │
│                                                             │
│  [ 응용 소프트웨어 / 제어 알고리즘 ]                        │
│  └──────────────────────────┬───────────────────────────────┘│
│                             ▼                               │
│  [ 실시간 운영체제(RTOS) / 하드웨어 추상화 계층(HAL) ]       │
│  └──────────────────────────┬───────────────────────────────┘│
│                             ▼                               │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ 임베디드 하드웨어 (MCU / SoC)                           ││
│  │ ┌─────────────────────────────────────────────────────┐ ││
│  │ │ 프로세서 코어 (ARM Cortex-M/R, RISC-V)              │ ││
│  │ ├──────────────────────┬──────────────────────────────┤ ││
│  │ │ 내부 메모리 (Flash/SRAM)│ 주변장치 (Timer/WDT/DMA)   │ ││
│  │ ├──────────────────────┴──────────────────────────────┤ ││
│  │ │ 통신 I/F (CAN / SPI / I2C / UART / ADC / DAC / PWM) │ ││
│  │ └─────────────────────────────────────────────────────┘ ││
│  └──────────────┬───────────────────────────┬──────────────┘│
│                 ▼                           ▼               │
│  [ 센서 & 입력 장치 ]                [ 액추에이터 & 모터 ]  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 상위 제어 소프트웨어가 RTOS/HAL을 통해 하드웨어 MCU를 구동하고 센서 신호 수신 및 액추에이터 제어 실행

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 코어 (MCU/MPU) | 센싱 데이터를 연산하고 제어 알고리즘 및 펌웨어 명령어를 실행 |
| 온칩 메모리 (Flash & SRAM) | 비휘발성 코드 영역(Flash)과 실시간 변수/스택 데이터 영역(SRAM) 제공 |
| 입출력 주변장치 (ADC/PWM) | 아날로그 센서 값을 디지털로 변환(ADC)하고 모터 듀티비를 제어(PWM) |
| 통신 인터페이스 (CAN/SPI) | 외부 센서, 액추에이터 및 상위 ECU/호스트와 결정적 데이터 패킷 송수신 |
| 안전 보호 회로 (WDT/BOR) | 전압 강하 감지(Brown-Out Reset) 및 시스템 프리징 시 자동 재부팅 수행 |

#### 한줄 요약
- 프로세서 코어, 온칩 메모리, 주변장치(ADC/PWM), 통신 버스, 안전 회로(WDT), RTOS가 하나의 완결된 구조를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인터럽트 서비스 루틴(ISR)**: 센서 감지나 타이머 만료 등 긴급 외부 이벤트 발생 시 CPU가 즉각 분기해 최우선 처리하는 핸들러.

</details>

```text
시스템 전원 인가 및 하드웨어 리셋 해제
      │
      ▼
1. 부트로더 기동: 클록 설정, 스택 초기화, 펌웨어 무결성 검증
      │
      ▼
2. RTOS 커널 시작: 태스크 생성, 타이머 구동, 우선순위 스케줄링 가동
      │
      ▼
3. 센서 데이터 취득: ADC/I2C 인터럽트 발생 및 버퍼 저장
      │
      ▼
4. 제어 알고리즘 연산: PID 제어, 필터링 연산 및 PWM 구동값 산출
      │
      ▼
5. 액추에이터 구동 & 워치독 갱신: 모터 출력 후 WDT 카운터 클리어(Kick)
```

**동작 원리**

1. **하드웨어 초기화**: 전원 안정화 후 부트로더가 레지스터와 클록을 초기화하고 플래시에서 코드 로드
2. **RTOS 스케줄러 실행**: 제어 태스크들을 생성하고 선점형 우선순위 큐에 등록하여 디스패치
3. **이벤트 인터럽트 인입**: 외부 센서 변화 시 ISR이 즉시 발생하여 데이터를 읽고 태스크로 시그널 전송
4. **결정적 제어 연산**: 마감시간 내에 모터 궤적 및 밸브 제어 알고리즘을 연산
5. **안전 감시 갱신**: 제어 신호를 출력한 직후 워치독 타이머를 갱신하여 정상 동작 상태 확인

#### 한줄 요약
- 부팅 초기화 → RTOS 가동 → 센서 인터럽트 취득 → 제어 연산 → 출력 및 워치독 갱신 순으로 무한 루프 동작한다.

## Ⅴ. 종류 및 비교

| 임베디드 제어 코어 | MCU (마이크로컨트롤러) | MPU / SoC | DSP (신호처리) | FPGA (재구성 로직) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 모터 제어·가전·센서 노드 초저전력 | 스마트TV·게이트웨이·리눅스 탑재 기기 | 오디오/레이더/영상 실시간 필터링 | 초고속 통신 프로토콜 및 하드웨어 가속 |
| 핵심 특징 | 단일 칩 내부 Flash/RAM/I/O 집적 | 고성능 코어(GHz)+외장 DDR 메모리 | 고속 MAC 연산기 및 하버드 아키텍처 | 비트스트림 기반 순수 하드웨어 파이프라인 |
| 한계 | 메모리 용량 부족 및 복잡한 GUI 불가 | 높은 대기 전력 소모 및 복잡한 전원 회로 | 범용 제어 로직 구현 비효율 | 높은 칩 단가 및 복잡한 HDL 개발 난이도 |

#### 한줄 요약
- 단순 제어는 MCU, 고성능 리눅스는 MPU, 신호처리는 DSP, 초저지연 하드웨어는 FPGA를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **A/B 듀얼 뱅크 펌웨어 업데이트(A/B OTA)**: 플래시 메모리를 두 파티션으로 나누어 신규 펌웨어를 B에 쓰고 부팅 성공 검증 후 활성화하는 안전 업데이트 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 펌웨어 무선 업데이트(OTA) 중 정전 시 **디바이스 벽돌(Bricking) 현상** | **A/B 듀얼 뱅크 플래시** 파티션 및 롤백 부트로더 구축 | 전원 차단 시에도 이전 정상 버전 자동 복구 |
| 소프트웨어 무한 루프로 인한 **시스템 프리징(Freezing)** | 하드웨어 **윈도우 워치독(Windowed WDT)** 독립 구성 | 비정상 정지 시 밀리초 단위 자동 강제 리셋 |
| 배터리 구동 엣지 장치의 **과도한 배터리 소모** | **저전력 딥슬립(Deep Sleep)** 모드 및 외부 핀 인터럽트 웨이크업 | 배터리 수명 수년 이상 연장 |
| 산업 현장 EMI/노이즈로 인한 **센서 신호 왜곡** | **차동 신호(CAN/RS-485)** 채택 및 하드웨어 RC 필터/옵토커플러 장착 | 노이즈 내성 강화 및 통신 무결성 보장 |

#### 한줄 요약
- A/B OTA로 벽돌을 막고, 윈도우 WDT로 프리징을 잡으며, 딥슬립과 CAN 통신으로 전력과 노이즈를 다스린다.

## Ⅶ. 결론

- 초저전력 초저비용 센서 제어는 **MCU + RTOS**, 고성능 네트워크 및 GUI 탑재는 **MPU + 임베디드 리눅스** 선택

#### 한줄 요약
- 하드웨어와 소프트웨어의 공동 설계를 바탕으로 실시간 제어성과 시스템 안전성을 통합 달성해야 한다.
