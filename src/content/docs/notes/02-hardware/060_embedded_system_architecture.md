## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **임베디드 시스템(Embedded System)**: 특정 장치 기능을 수행하도록 하드웨어와 펌웨어를 결합한 전용 컴퓨터이다.
- **펌웨어(Firmware)**: 장치에 내장되어 센서와 프로세서 및 주변 하드웨어를 직접 제어하는 소프트웨어이다.
- **하드웨어•소프트웨어 분할(Hardware-software Partitioning)**: 시간과 전력 및 변경 요구에 따라 기능을 전용 회로와 펌웨어 중 어디에서 실행할지 나누는 설계 방식이다.

</details>

- 정의/개념: 제한된 연산·메모리·전력 자원에서 특정 장치의 센서 입력, 제어와 통신 기능을 수행하는 **임베디드 시스템**이다.
- 배경/필요성: 범용 컴퓨터는 고정 장치 기능에 불필요한 자원과 소프트웨어 계층을 포함해 비용·전력·응답 시간 변동이 증가한다.

#### 한줄 요약

- 임베디드 시스템은 제한된 자원 안에서 센서 입력을 처리하고 정해진 시간에 제어 출력을 생성하도록 하드웨어와 펌웨어를 결합한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **마감시간(Deadline)**: 제어 작업의 결과가 반드시 완료되어 출력에 반영되어야 하는 시점이다.
- **실시간 입출력(Real-time I/O)**: 센서 입력부터 액추에이터 출력까지 정해진 시간 한도 안에 처리하는 동작이다.
- **제한 자원(Resource Constraint)**: 메모리와 연산 성능 및 배터리 용량이 제품 비용과 크기에 따라 제한되는 조건이다.

</details>

- **마감시간**이 짧고 반복되는 기능은 전용 하드웨어, 변경이 잦고 복잡한 제어는 펌웨어에 배치한다.
- **실시간 입출력**으로 정해진 응답 시간을 준수한다.
- **제한 자원** 안에서 기능과 확장·변경 범위를 결정한다.

#### 한줄 요약

- 마감시간·전력·변경 요구를 함께 비교해 기능을 전용 회로 또는 펌웨어로 분할한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **입력부(Input Unit)**: 센서 신호를 변환하고 인터럽트로 처리부에 전달하는 구성이다.
- **처리•제어부(Processing and Control Unit)**: 프로세서와 실시간 운영체제(Real-Time Operating System, RTOS)로 실시간 작업을 실행하는 구성이다.
- **메모리부(Memory Unit)**: 펌웨어 코드와 설정 및 실행 상태를 보관하는 구성이다.
- **통신부(Communication Unit)**: 운용 데이터와 펌웨어 이미지를 송수신하는 구성이다.
- **출력•복구부(Output and Recovery Unit)**: 제어 신호를 전달하고 오류 시 안전 출력과 재부팅을 수행하는 구성이다.

</details>

```text
                         [메모리부]
                              |
[입력부] ----- [처리•제어부] ----- [통신부]
                      |
                [출력•복구부]
```

선의 의미: 선은 처리•제어부를 중심으로 입력, 메모리, 통신과 출력•복구 기능이 결합되는 정적 시스템 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 입력부 | 센서 신호 변환•인터럽트 전달 |
| 처리•제어부 | 실시간 작업 실행 |
| 메모리부 | 코드•상태 보관 |
| 통신부 | 데이터•업데이트 수신 |
| 출력•복구부 | 제어•안전 출력 |

#### 한줄 요약

- 입력부의 센서값을 처리·제어부가 계산해 출력부에 반영하고, 오류 시 워치독과 안전 출력이 위험 동작을 제한한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **제어 주기(Control Cycle)**: 센서 읽기와 계산 및 출력 갱신을 반복하는 고정 시간 간격이다.
- **워치독(Watchdog)**: 정해진 시간 동안 정상 완료 보고가 없는 펌웨어를 감지하여 안전 출력이나 재시작을 실행하는 장치이다.
- **안전 상태(Safe State)**: 오류나 마감시간 초과 때 액추에이터를 정지하거나 제한하여 위험을 줄이는 출력 상태이다.
- **검증 이미지(Validated Image)**: 무결성과 정상 동작을 확인하여 장애 복구 시 부팅할 수 있는 펌웨어 이미지이다.
- **입력 변환·상태 조회**: 센서값을 디지털 상태로 바꾸고 목표값과 이전 상태를 읽는 단계이다.
- **실시간 제어 연산**: 제어 주기와 우선순위에 따라 액추에이터 출력값을 계산하는 단계이다.
- **제어 출력 적용**: 계산한 명령을 마감시간 안에 액추에이터에 반영하는 단계이다.
- **안전 출력 전환**: 시간 초과나 펌웨어 정지 시 액추에이터를 안전 상태로 바꾸는 단계이다.
- **워치독 리셋·오류 복구**: 고장 정보를 기록하고 검증 이미지로 시스템을 다시 시작하는 단계이다.

</details>

```text
 [센서•물리 플랜트]
          |
 1. 입력 변환•상태 조회
          |
 2. 실시간 제어 연산
          |
 3. 제어 출력 적용
          |
   [마감시간 내 완료?]
      ├─ 예
      │  └─ [워치독 갱신 후 제어 주기 반복]
      └─ 아니요•정지
         └─ 4. 안전 출력 전환
            └─ 5. 워치독 리셋·오류 복구
               └─ [제어 주기 재시작]
```

### 동작 원리

1. **입력 변환·상태 조회**: 센서값을 디지털 상태로 바꾸고 목표값과 이전 제어 상태를 확보한다.
2. **실시간 제어 연산**: RTOS 작업 또는 전용 회로가 제어 주기와 우선순위에 따라 출력값을 계산한다.
3. **제어 출력 적용**: 계산한 명령을 마감시간 안에 액추에이터에 반영하고 정상 완료 상태를 기록한다.
4. **안전 출력 전환**: 마감시간 초과나 펌웨어 정지 시 액추에이터를 제한·정지하는 **안전 상태**로 전환한다.
5. **워치독 리셋·오류 복구**: 고장 원인을 기록하고 시스템을 재시작하며 부팅 검증 실패 시 A/B 파티션의 **검증 이미지**로 복귀한다.

#### 한줄 요약

- 제어 주기를 마감시간 안에 끝내면 워치독을 갱신하고, 시간 초과나 정지 시 안전 출력을 적용한 뒤 복구 절차를 실행한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **마이크로컨트롤러(Microcontroller Unit, MCU)**: 프로세서 코어와 메모리 및 제어용 주변장치를 하나의 칩에 통합한 장치이다.
- **마이크로프로세서(Microprocessor Unit, MPU)**: 외부 메모리와 주변장치를 연결하여 고기능 운영체제를 실행하는 범용 처리장치이다.
- **시스템온칩(System on Chip, SoC)**: 연산과 가속 및 메모리 제어•주변 기능을 하나의 다이에 통합한 칩이다.

</details>

| 임베디드 시스템 | MCU 기반 | MPU•SoC 기반 |
|:---|:---|:---|
| 적용 기준 | 센서•모터•단순 통신 제어 | 화면•네트워크•대용량 처리 |
| 핵심 특징 | **MCU**의 온칩 저전력 실시간 제어 | **MPU·SoC**의 외부 메모리•운영체제 처리 |
| 한계 | 메모리•연산 확장 제한 | 지연 변동•전력 증가 |

#### 한줄 요약

- 저전력·단순 실시간 제어에는 MCU가, 화면·네트워크·대용량 메모리가 필요한 고기능 처리에는 MPU·SoC가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **최악 실행 시간(Worst-case Execution Time, WCET)**: 지정한 하드웨어와 입력 및 간섭 조건에서 작업 완료에 걸릴 수 있는 최대 시간이다.
- **차단 시간(Blocking Time)**: 높은 우선순위 작업이 공유 자원을 점유한 낮은 우선순위 작업 때문에 기다리는 시간이다.
- **A/B 파티션(A/B Partition)**: 새 펌웨어와 이전 정상 펌웨어를 별도 영역에 보관하여 실패 시 복귀할 수 있게 한 구성이다.
- **하드웨어 연동 검증(Hardware-in-the-loop, HIL)**: 실제 제어기와 실시간 모의 플랜트를 연결하여 센서•액추에이터 입출력을 검증하는 방식이다.
- **무선 펌웨어 업데이트(Over-the-air Update, OTA)**: 통신망으로 새 펌웨어 이미지를 장치에 전송하고 설치하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 실행·**차단 시간**이 예상보다 길어 제어 마감시간 초과 | 공유 자원 차단을 포함한 **WCET** 분석과 최악 부하 시험 | 응답 상한을 검증해 결정적 제어 주기 확보 |
| 워치독 시간이 너무 짧거나 길어 정상 작업 오탐·고장 탐지 지연 | 정상 최악 실행 시간과 복구 목표를 기준으로 워치독 주기 설정 | 오탐을 피하면서 고장 탐지 시간 제한 |
| **OTA** 기록 중 전원이 끊겨 펌웨어 이미지 손상 | 서명 검증과 **A/B 파티션**의 원자적 전환·롤백 적용 | 이전 정상 이미지로 부팅해 업데이트 복원력 확보 |
| 제어 오류 후 액추에이터가 위험 출력을 유지해 안전 사고 가능 | 센서·통신·마감시간 오류의 **HIL** 장애 주입 시험 | 오류별 제한·정지 출력으로 안전 상태 검증 |

#### 한줄 요약

- HIL 장애 주입으로 마감시간 초과와 통신·센서 오류를 재현해 안전 출력과 워치독 복구 절차를 검증한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **저전력 실시간 제어(Low-power Real-time Control)**: 작은 에너지 예산 안에서 센서 입력과 제어 출력을 마감시간 내 처리하는 작업이다.
- **고기능 처리(Feature-rich Processing)**: 화면과 네트워크 및 대용량 데이터처럼 운영체제와 외부 메모리가 필요한 작업이다.
- **결정적 응답(Deterministic Response)**: 지정 조건에서 응답 시간이 예측 가능한 상한 안에 머무는 성질이다.
- **임베디드 처리 구조 선택 기준**: 전력·마감시간과 기능 복잡도로 MCU와 MPU·SoC를 고르는 기준이다.

</details>

- **임베디드 처리 구조 선택 기준**에 따라 **결정적 응답**과 **저전력 실시간 제어**가 우선이면 **MCU**, 운영체제·화면·대용량 통신의 **고기능 처리**가 우선이면 **MPU·SoC**를 선택한다.

#### 한줄 요약

- 마감시간·전력 한도가 우선이면 MCU를, 운영체제·화면·대용량 통신 등 기능 복잡도가 우선이면 MPU·SoC를 선택한다.
