## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 특정 목적의 전자기기나 기계 장치 내부에 내장되어 제어, 통신, 센싱을 전담하는 하드웨어·소프트웨어 통합 컴퓨팅 시스템.

</details>

- 정의/개념: 특정 제어 목적에 맞춰 프로세서, 온칩 메모리, 주변장치와 전용 펌웨어를 최적화한 **임베디드 시스템**
- 배경/필요성: 기존 범용 컴퓨터 구조로는 **전력·원가·소형화·실시간 마감시간 제약 동시 충족 불가**

#### 한줄 요약
- 임베디드 시스템은 제한된 하드웨어 자원과 엄격한 실시간성 및 신뢰성 요구조건을 충족하기 위한 특화 제어 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **실시간성(Real-Time Property)**: 논리적인 연산 결과의 정확성뿐만 아니라 정해진 시간 제약(Deadline) 내에 결과를 출력해야 하는 특성.
- **자원 제약성(Resource Constraint)**: 배터리 수명, 초소형 패키지 면적, 제한된 메모리 용량(KB~MB 단위) 내에서 동작해야 하는 하드웨어 제약.
- **HW/SW 공동 설계(HW/SW Co-Design)**: 목표 성능, 전력, 비용 요구사항에 맞춰 기능을 하드웨어 회로와 소프트웨어 알고리즘으로 최적 분할하는 설계 방법론.

</details>

- **HW/SW 공동 설계** 기반으로 하드웨어 회로와 소프트웨어 기능 간 최적 분할
- **실시간성** 보장을 위한 결정론적(Deterministic) 최악 실행 시간(WCET) 관리
- 엄격한 **자원 제약성** 환경에서 고온·진동·전자파 노이즈를 견디는 고신뢰성 요구

#### 한줄 요약
- 하드웨어와 소프트웨어를 동시에 설계하여 자원 제약 내에서 확정적 실시간 응답성을 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워치독 타이머(Watchdog Timer, WDT)**: 소프트웨어가 무한 루프나 다운 상태에 빠졌을 때 주기적 신호(Kick) 부재를 감지해 시스템을 강제 리셋하는 하드웨어 타이머.
- **액추에이터(Actuator)**: 전기 제어 신호를 모터 회전, 밸브 개폐, 릴레이 동작 등 물리적 운동으로 변환하는 장치.

</details>

```text
[임베디드 시스템 계층]
|-- 응용 계층 (제어 알고리즘·상태 머신)
|-- 미들웨어 / RTOS (스케줄러·HAL·드라이버)
|-- MCU / SoC 하드웨어
|   |-- 프로세서 코어 (ARM Cortex-M 등)
|   |-- 온칩 메모리 (Flash·SRAM)
|   |-- 제어 타이머·워치독 타이머(WDT)·DMA·ADC
|   `-- 통신 인터페이스 (CAN·SPI·I2C·UART)
`-- 센서 및 액추에이터 (물리 환경 인터페이스)
```

선의 의미: 계층 및 신호 입출력 구조

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 코어 | 센싱 데이터 연산 및 제어 알고리즘의 실시간 실행 |
| 온칩 메모리 | 비휘발성 코드 영역(Flash)과 실행 중 변수·스택 영역(SRAM) 제공 |
| 입출력 주변장치 | 아날로그-디지털 변환(ADC) 및 **액추에이터** 구동 신호(PWM) 생성 |
| 통신 인터페이스 | CAN, SPI, I2C 버스를 통한 센서·모듈 간 결정적 데이터 통신 |
| **워치독 타이머(WDT)** | 소프트웨어 비정상 다운 감지 시 시스템 강제 하드웨어 리셋 |

#### 한줄 요약
- MCU, 온칩 메모리, 주변 I/O, 센서/액추에이터 및 RTOS가 결합되어 밀결합된 제어 루프를 형성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인터럽트 서비스 루틴(ISR)**: 센서 감지나 타이머 만료 등 긴급 외부 이벤트 발생 시 CPU가 즉각 분기해 최우선 처리하는 핸들러.

</details>

```text
전원 인가 → 부트로더가 클록·레지스터 초기화
        │
   RTOS 스케줄러 기동 후 태스크 등록
        │
   외부 이벤트 발생 (주기적 타이머 / 센서 인터럽트)
        │
   인터럽트 서비스 루틴(ISR)이 데이터 취득 후 태스크 통지
        │
   마감시간(Deadline) 안에 제어 연산이 끝났는가?
   ┌────┴─────┐
  예           아니오
   │             │
제어값 출력 후   워치독 미갱신 ->
워치독 갱신      강제 리셋 및 Fail-Safe 진입
   └────┬────────┘
        │
   다음 제어 주기 대기
```

#### 한줄 요약
- 인터럽트 발생 → ISR 데이터 취득 → 마감시간 내 제어 연산 및 출력 → 워치독 갱신 순으로 실시간 루프가 반복된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MCU(Microcontroller Unit)**: 단일 칩 내에 CPU, 메모리, 타이머, I/O를 통합한 초소형 제어 전용 프로세서.
- **MPU/SoC**: 외장 고속 메모리와 OS(Linux 등)를 구동할 수 있는 고성능 임베디드 프로세서.

</details>

| 임베디드 제어 코어 | MCU (마이크로컨트롤러) | MPU / SoC | DSP (신호처리) | FPGA (재구성 로직) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 모터 제어·가전·센서 노드 초저전력 | 스마트TV·게이트웨이·리눅스 탑재 기기 | 오디오/레이더/영상 실시간 필터링 | 초고속 통신 프로토콜 및 하드웨어 가속 |
| 핵심 특징 | 단일 칩 내부 Flash/RAM/I/O 집적 | 고성능 코어(GHz)+외장 DDR 메모리 | 고속 MAC 연산기 및 하버드 아키텍처 | 비트스트림 기반 순수 하드웨어 파이프라인 |
| 한계 | 메모리 용량 부족 및 복잡한 GUI 불가 | 높은 대기 전력 소모 및 복잡한 전원 회로 | 범용 제어 로직 구현 비효율 | 높은 칩 단가 및 복잡한 HDL 개발 난이도 |

#### 한줄 요약
- 단순 저전력 제어에는 MCU, 복잡한 네트워크/GUI에는 MPU/SoC, 고속 디지털 신호처리에는 DSP/FPGA를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **A/B 듀얼 뱅크 펌웨어 업데이트(A/B OTA)**: 플래시 메모리를 두 파티션으로 나누어 신규 펌웨어를 B에 쓰고 부팅 성공 검증 후 활성화하는 안전 업데이트 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 원격 업데이트 중 전원 차단 시 벽돌(Brick) 현상 | **A/B 듀얼 뱅크 펌웨어 업데이트** 및 롤백 부트로더 구축 | 전원 차단에도 이전 정상 버전 자동 복구 |
| 소프트웨어 무한 루프로 인한 시스템 멈춤 | 윈도우 워치독(WDT) 적용 및 갱신 주기 엄격 검증 | 너무 이르거나 늦은 갱신 감지 시 자동 리셋 |
| 배터리 구동 단말의 대기 전력 소모 | 딥슬립(Deep Sleep) 모드 및 인터럽트 웨이크업 | 듀티 사이클 최적화로 배터리 수명 수년 연장 |
| 산업 현장 모터 노이즈로 센서 신호 왜곡 | 차동 신호(RS-485/CAN) 및 포토커플러 절연 회로 | 노이즈 내성 강화 및 제어 안정성 확보 |

#### 한줄 요약
- A/B 듀얼 뱅크 OTA로 안정성을 확보하고, 윈도우 워치독과 딥슬립 모드로 신뢰성과 저전력을 구현한다.

## Ⅶ. 결론

- 엄격한 실시간성과 자원 제약 환경은 **MCU 기반 RTOS 아키텍처**를 구축하고, 복잡한 통신 및 AI 연산 요구 시 **MPU/SoC 이기종 구조**로 확장 설계

#### 한줄 요약
- 임베디드 아키텍처 설계는 하드웨어 자원 한계 내에서 실시간 마감시간 준수와 무중단 신뢰성을 보장하는 것이 핵심이다.
