## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 특정 제어 목적(자동차 전장, 산업용 로봇, 스마트 가전 등)만을 수행하도록 프로세서, 메모리, I/O 및 전용 펌웨어를 통합한 컴퓨팅 시스템.
- **펌웨어(Firmware)**: 비휘발성 ROM/Flash 메모리에 상주하여 하드웨어 레지스터와 직접 통신하며 실시간 제어를 수행하는 임베디드 소프트웨어.
- **HW/SW Partitioning(하드웨어/소프트웨어 분할)**: 시스템 요구사항 중 고속 성능이 필요한 부분은 하드웨어 회로(FPGA/ASIC)로, 유연성이 필요한 부분은 소프트웨어(C/C++)로 분할하는 설계 기법.

</details>

- 정의/개념: 제한된 전력, 메모리 및 연산 자원 환경에서 특정 제어 기능(자동차 전장, 로보틱스, IoT)만을 전담 수행하기 위해 프로세서(MCU/MPU), 온칩 메모리, I/O 인터페이스 및 전용 펌웨어를 긴밀히 결합한 컴퓨터 시스템 구조
- 배경/필요성: 범용 컴퓨팅 아키텍처로는 충족하기 어려운 **초저전력(mW), 초저비용(BOM), 극한의 신뢰성 및 서브 밀리초(Sub-ms) 단위 실시간 제어 마감시간(Deadline) 보장 필수**

#### 한줄 요약

- 제한된 자원 환경에서 **특정 제어 목적을 위해 HW/SW를 최적 결합한 전용 시스템**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Deadline(마감시간)**: 시스템이 외부 이벤트에 반응하여 연산을 완료하고 제어 출력을 내보내야 하는 시간적 한계.
- **Real-Time I/O(실시간 입출력)**: OS 지연 없이 하드웨어 인터럽트(ISR)와 GPIO/ADC/PWM 핀을 통해 즉각적인 센싱 및 구동 제어 수행.
- **Resource Constraints(자원 제약)**: 수십 KB~수 MB의 작은 SRAM/Flash 용량과 mW 단위의 저전력 배터리 동작 환경.

</details>

- 외부 자극에 대해 정해진 시간 내에 무조건 반응해야 하는 **실시간 마감시간(Deadline) 엄수성**
- OS 커널 오버헤드를 배제하고 센서 및 모터 핀을 직접 구동하는 **저지연 실시간 입출력(Real-Time I/O)**
- 배터리 수명 극대화 및 BOM 원가 절감을 위한 **제한된 하드웨어 자원(Resource Constraints) 최적화**
- 기능 복잡도와 시간 제약에 따른 최적의 **하드웨어/소프트웨어 분할(HW/SW Partitioning)** 설계

#### 한줄 요약

- **실시간 마감시간 엄수(Determinism)·제한 자원 최적화(KB 단위 SRAM)·HW/SW Co-Design 분할**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **MCU(Microcontroller Unit)**: CPU 코어, Flash 메모리, SRAM, 타이머, ADC, 통신 채널을 단일 실리콘 다이에 통합한 원칩 프로세서.
- **Watchdog Timer(워치독 타이머)**: 소프트웨어가 무한 루프나 데드락에 빠져 정해진 시간 내에 킥(Kick)하지 않으면 시스템을 강제 리셋하는 하드웨어 타이머.

</details>

```text
[ 임베디드 시스템 하드웨어 및 펌웨어 계층 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 3. 온칩 메모리부 : Flash ROM (코드 상주) + SRAM (런타임 스택)│
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 2. 처리 제어부 : MCU 코어 (ARM Cortex-M / RISC-V) + NVIC     │
└──────┬───────────────────────┼───────────────────────┬──────┘
       │                       │                       │
┌──────▼──────┐         ┌──────▼──────┐         ┌──────▼──────┐
│ 1. 센서 입력부│        │ 4. 직렬 통신부│        │ 5. 출력/복구부│
│ (ADC, GPIO, │         │ (CAN, SPI,   │         │ (PWM 타이머, │
│  센서 I2C)  │         │  UART, LIN)  │         │  Watchdog)   │
└─────────────┘         └─────────────┘         └─────────────┘
```

선의 의미: 센서 입력부(ADC), 처리 제어부(MCU 코어), 온칩 메모리(Flash/SRAM), 통신부(CAN/SPI) 및 출력/복구부(PWM/Watchdog) 간의 임베디드 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 센서 입력부 | 아날로그 온도/압력 센서 신호를 쑤셔 넣고 0101 디지털(ADC)로 번역함 |
| 뇌하수체 처리 제어부 | 마이크로컨트롤러(MCU) 코어가 타이머를 쪼개며 실시간 태스크를 멱살 잡고 스케줄링함 |
| 메모리부 | 전원이 꺼져도 절대 안 날아가는 Flash 롬에 펌웨어 코드를 문신처럼 새겨서 저장함 |
| 직렬 통신부 | 자동차 안의 다른 부품들과 CAN이나 SPI 버스로 끊임없이 데이터를 주고받음 |
| 출력 복구부 | 모터나 밸브를 냅다 돌리고, 펌웨어가 뻗으면 **워치독**이 강제로 재부팅 버튼을 눌러버림 |

#### 한줄 요약

- **센서 입력부(ADC/GPIO)·MCU 처리 제어부·온칩 메모리(Flash/SRAM)·직렬 통신부·출력/워치독(WDT)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Fail-Safe Mode(안전 상태)**: 센서 오동작이나 마감시간 초과 시 모터 출력을 즉시 차단하고 브레이크를 체결하는 비상 안전 모드.

</details>

```text
[ 임베디드 센싱-제어-워치독 리셋 무한 루프 흐름 ]
                         │
                         ▼
   [ 1. 센서 인터럽트 발생 및 ADC 아날로그 $\to$ 디지털 변환 ]
                         │
                         ▼
   [ 2. MCU 코어가 실시간 PID/필터링 제어 알고리즘 연산 수행 ]
                         │
                         ▼
   [ 3. 마감시간(Deadline) 내에 모터 구동 PWM 제어 핀 신호 출력 ]
                         │
        +─────────────────────────────────────────+
        │             [ 정상 마감시간 내 완료? ] │
        │             /                         \ │
        │         [ 예 ]                      [ 아니오 ]
        │           │                             │
        │   4. 워치독 타이머 킥(Kick)     5. Fail-Safe 안전 출력 전환
        │      (다음 제어 주기 대기)         및 워치독 하드웨어 리셋
        +─────────────────────────────────────────+
```

**동작 원리**

1. **센싱 및 인터럽트**: 외부 센서 전압 변화 시 ADC 변환 완료 인터럽트가 CPU를 즉각 트리거
2. **실시간 제어 연산**: 인터럽트 서비스 루틴(ISR) 또는 RTOS 고우선순위 태스크가 제어 수식 연산
3. **액추에이터 출력**: 계산된 제어값을 마감시간 내에 PWM/DAC 핀으로 인가하여 모터/밸브 조작
4. **워치독 킥**: 제어 사이클이 정상 완료되면 워치독 타이머 레지스터를 갱신(Kick/Pet)하여 카운트 초기화
5. **Fail-Safe 복구**: 시스템 행(Hang) 또는 마감시간 위반 시 워치독이 타임아웃되어 전원 강제 리셋 및 안전 정지

#### 한줄 요약

- 센서 입력 인입 $\to$ **실시간 제어 연산 $\to$ 마감시간 내 PWM 액추에이터 출력 $\to$ 정상 시 WDT 킥 / 타임아웃 시 Fail-Safe 리셋**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MCU vs MPU vs DSP**:
  - MCU: 원칩(CPU+Flash+RAM), Bare-metal/RTOS, mW 단위 초저전력, 단순 제어
  - MPU/SoC: 외장 DRAM/Flash, Linux/Android, 수 W 전력, 복합 GUI/네트워크
  - DSP: 고성능 MAC 어레이, 오디오/통신 신호처리 특화

</details>

| 비교 항목 | MCU 기반 구조 (Microcontroller) | MPU / SoC 기반 구조 (Microprocessor) | DSP 기반 구조 (신호처리 프로세서) |
|:---|:---|:---|:---|
| 집적도 및 메모리 | CPU + Flash + SRAM + I/O 단일 칩 통합 (On-Chip) | 프로세서 코어 + 외부 LPDDR/DRAM + 외부 Flash | MAC 가속기 + 하버드 내부 SRAM 버스 |
| 운영체제 및 전력 | Bare-metal 또는 경량 RTOS (FreeRTOS, $\text{mW}$ 단위) | 임베디드 리눅스, Android, QNX (수 $\text{W}$ 단위) | 전용 DSP RTOS 또는 베어메탈 펌웨어 |
| 한계 및 적합 분야 | 소용량 메모리로 대용량 AI/GUI 처리 불가 (센서/모터) | 부팅 지연 및 비결정론적 지연 (스마트 디스플레이) | 범용 제어 로직 처리 시 비효율적 (오디오/레이더) |

#### 한줄 요약

- 초저전력 실시간은 **MCU**, 고성능 OS/GUI는 **MPU/SoC**, 신호 연산은 **DSP**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **WCET(Worst-Case Execution Time)**: 모든 분기 조건과 캐시 미스 발생을 가정한 태스크의 수학적 최악 실행 시간.
- **A/B Dual-Bank Flash**: 플래시 메모리를 Bank A와 Bank B로 분할하여 무중단 OTA 펌웨어 업데이트 및 오류 시 즉각 롤백을 구현하는 기술.
- **HIL(Hardware-in-the-Loop)**: 실제 센서/모터 대신 실시간 시뮬레이터를 MCU I/O 핀에 연결하여 가상 고장 주입 및 한계 상황을 검증하는 시험 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 펌웨어 코드를 발로 짜서 **마감시간**을 놓쳐 브레이크가 안 밟히는 끔찍한 오작동 대참사 | 코드의 **최악 실행 시간**(WCET)을 뼛속까지 분석하여 RTOS 타이머 우선순위를 칼같이 멱살 잡고 재배치 | 어떤 악조건에서도 0.01초 안에 무조건 반응하는 지독한 실시간 결정성 100% 확보 달성 |
| 자동차 펌웨어 무선 업데이트(OTA) 중 인터넷이 끊겨 자동차가 쇳덩이(벽돌)가 되는 끔찍한 셧다운 위험 | 칩 안에 메모리 뱅크를 두 개(A/B)로 쪼개어, 펌웨어 갱신 실패 시 예전 코드로 냅다 롤백(**에이비 파티션**) | 실패한 펌웨어 업데이트 때문에 장비가 먹통이 되는 끔찍한 A/S 사태를 완벽하게 예방 및 복구 |
| 실제 자동차에 보드를 달고 극한 테스트하다가 브레이크가 안 들어 연구원이 벽에 처박히는 사망 위험 | 진짜 센서 대신 컴퓨터로 뻥튀기 신호를 쏴주는 가상 시뮬레이터(**에이치아이엘**) 기반 십자포화 테스트 수행 | 사람이 다치지 않고도 수만 번의 기괴한 고장 주입 테스트를 돌려 안전 출력 및 복구 절차를 완벽 검증 |

#### 한줄 요약

- **WCET 최악 실행시간 분석·A/B 듀얼 뱅크 무중단 OTA·HIL(Hardware-in-the-Loop) 시뮬레이션**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **이종 멀티코어 임베디드 SoC 트렌드**: 실시간 안전 제어용 Cortex-M 코어 + 고성능 AI/GUI 처리용 Cortex-A 코어를 단일 칩에 통합하여 복합 시스템 구축.

</details>

- 임베디드 제어 시스템에서 **하드 실시간 제어는 ARM Cortex-M 기반 MCU 표준 채택 및 복합 멀티미디어는 Cortex-A MPU/SoC 분할 설계 적용**

#### 한줄 요약

- **실시간 결정론(Deadline)과 전력/원가 예산(BOM)**에 맞춘 MCU vs MPU 구조 선정
