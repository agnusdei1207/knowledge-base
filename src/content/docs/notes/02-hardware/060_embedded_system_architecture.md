## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템(Embedded System)**: 특정 목적의 전자기기나 기계 장치 내부에 내장되어 제어, 통신, 센싱을 전담하는 하드웨어·소프트웨어 통합 컴퓨팅 시스템.
- **HW/SW 공동 설계(HW/SW Co-Design)**: 목표 성능, 전력, 비용 요구사항에 맞춰 기능을 하드웨어 회로와 소프트웨어 알고리즘으로 최적 분할하는 설계 방법론.

</details>

- 정의/개념: 제품 하나의 목적에 맞춰 프로세서·메모리·주변장치와 펌웨어를 함께 재단한 **임베디드 시스템(Embedded System)** 구조
- 배경/필요성: 제어·전력·원가·환경·마감시간이라는 다섯 제약을 동시에 만족시키려면 범용 구성으로는 어느 하나가 반드시 깨짐

#### 한줄 요약
- 이 분야에서 설계란 기능을 더하는 일이 아니라 다섯 제약이 서로 충돌하는 지점에서 무엇을 포기할지 정하는 일이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **실시간성(Real-Time Property)**: 논리적인 연산 결과의 정확성뿐만 아니라 정해진 시간 제약(Deadline) 내에 결과를 출력해야 하는 특성.
- **자원 제약성(Resource Constraint)**: 배터리 수명, 초소형 패키지 면적, 제한된 메모리 용량(KB~MB 단위) 내에서 동작해야 하는 하드웨어 제약.

</details>

- **HW/SW 공동 설계(HW/SW Co-Design)**로 같은 기능을 회로로 넣을지 코드로 둘지 결정
- **실시간성(Real-Time Property)**은 평균이 아니라 최악 실행시간 분석으로만 검증 가능
- **자원 제약성(Resource Constraint)** 아래에서 고온·진동·노이즈까지 견뎌야 하는 신뢰성 요구

#### 한줄 요약
- 기능을 회로로 옮기면 빨라지고 코드로 두면 고치기 쉬우므로, 이 경계선은 성능이 아니라 제품 수명 동안의 변경 가능성이 정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워치독 타이머(Watchdog Timer, WDT)**: 소프트웨어가 무한 루프나 다운 상태에 빠졌을 때 주기적 신호(Kick) 부재를 감지해 시스템을 강제 리셋하는 하드웨어 타이머.
- **액추에이터(Actuator)**: 전기 제어 신호를 모터 회전, 밸브 개폐, 릴레이 동작 등 물리적 운동으로 변환하는 장치.

</details>

```text
[임베디드 시스템 계층]
├─ 응용 소프트웨어·제어 알고리즘
├─ RTOS·하드웨어 추상화 계층
├─ MCU·SoC
│  ├─ 프로세서 코어
│  ├─ 온칩 메모리 (Flash·SRAM)
│  ├─ 주변장치 (Timer·워치독 타이머·DMA·ADC·PWM)
│  └─ 통신 인터페이스 (CAN·SPI·I2C·UART)
└─ 물리 계층
   ├─ 센서·입력 장치
   └─ 액추에이터·모터
```

선의 의미: 가지(`├─`)는 소유 관계이며, 위로 갈수록 변경이 쉽고 아래로 갈수록 양산 후 고칠 수 없음

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 코어 | 센싱 데이터 연산과 제어 알고리즘 실행 |
| 온칩 메모리 | 비휘발성 코드 영역과 실행 중 변수·스택 영역 제공 |
| 입출력 주변장치 | 아날로그 신호 변환과 **액추에이터(Actuator)** 구동 신호 생성 |
| 통신 인터페이스 | 외부 장치·상위 제어기와 결정적 데이터 송수신 |
| **워치독 타이머(Watchdog Timer, WDT)** | 신호 부재 감지 시 시스템 강제 리셋 |

#### 한줄 요약
- 감시 회로가 프로세서 밖에 따로 있는 이유는 소프트웨어가 멈췄을 때 그 소프트웨어에게 복구를 맡길 수 없기 때문이며, 안전 설계는 늘 이 독립성에서 출발한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인터럽트 서비스 루틴(ISR)**: 센서 감지나 타이머 만료 등 긴급 외부 이벤트 발생 시 CPU가 즉각 분기해 최우선 처리하는 핸들러.

</details>

```text
전원 인가 → 부트로더가 클록·레지스터 초기화
        │
   RTOS 스케줄러 기동 후 태스크 등록
        │
   외부 이벤트 발생
   ┌────┴─────────┐
주기적 타이머 만료   비동기 센서 변화
   │                 │
   └────┬────────────┘
        │
   인터럽트 서비스 루틴이 데이터 취득 후 태스크 통지
        │
   마감시간 안에 제어 연산이 끝났는가?
   ┌────┴─────┐
  예           아니오
   │             │
제어값 출력 후   워치독 미갱신 →
워치독 갱신      강제 리셋·안전 상태 진입
   └────┬────────┘
        │
   다음 주기 대기
```

분기 결과: 정상 경로와 실패 경로가 같은 워치독 갱신 지점에서 갈리므로, 감시 회로는 오류를 검출하는 것이 아니라 정상 동작의 증거가 끊긴 것을 검출

#### 한줄 요약
- 워치독을 무조건 갱신하도록 짜면 감시 기능이 통째로 무력해지므로, 이 회로의 값어치는 하드웨어가 아니라 갱신 조건을 어떻게 걸었는지에서 나온다.

## Ⅴ. 종류 및 비교

| 임베디드 제어 코어 | MCU (마이크로컨트롤러) | MPU / SoC | DSP (신호처리) | FPGA (재구성 로직) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 모터 제어·가전·센서 노드 초저전력 | 스마트TV·게이트웨이·리눅스 탑재 기기 | 오디오/레이더/영상 실시간 필터링 | 초고속 통신 프로토콜 및 하드웨어 가속 |
| 핵심 특징 | 단일 칩 내부 Flash/RAM/I/O 집적 | 고성능 코어(GHz)+외장 DDR 메모리 | 고속 MAC 연산기 및 하버드 아키텍처 | 비트스트림 기반 순수 하드웨어 파이프라인 |
| 한계 | 메모리 용량 부족 및 복잡한 GUI 불가 | 높은 대기 전력 소모 및 복잡한 전원 회로 | 범용 제어 로직 구현 비효율 | 높은 칩 단가 및 복잡한 HDL 개발 난이도 |

#### 한줄 요약
- 네 코어의 갈림길은 성능이 아니라 응답 시간을 보장할 수 있는가이며, 성능이 올라갈수록 최악 지연을 예측하기는 오히려 어려워진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **A/B 듀얼 뱅크 펌웨어 업데이트(A/B OTA)**: 플래시 메모리를 두 파티션으로 나누어 신규 펌웨어를 B에 쓰고 부팅 성공 검증 후 활성화하는 안전 업데이트 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 원격 업데이트 중 정전으로 기기 복구 불능 | **A/B 듀얼 뱅크 펌웨어 업데이트(A/B OTA)**와 롤백 부트로더 구축 | 전원 차단에도 이전 정상 버전 자동 복구 |
| 무한 루프로 제어가 멈춘 채 전원만 유지 | 갱신 시점 상한·하한을 모두 검사하는 워치독 구성 | 너무 이르거나 늦은 갱신을 감지해 안전 상태 전환 |
| 배터리 구동 장치의 대기 전력 과다 | 딥슬립과 이벤트 기반 웨이크업 적용 | 듀티 사이클과 평균 소비 전력 감소 |
| 산업 현장 노이즈로 센서 신호 왜곡 | 차동 신호 방식 채택과 필터·절연 소자 장착 | 노이즈 내성 강화와 통신 무결성 확보 |

#### 한줄 요약
- 네 대책 모두 정상 동작이 아니라 실패 상황을 겨냥하는데, 손이 닿지 않는 곳에 설치되는 기기에서는 복구 가능성이 성능보다 먼저 요구된다.

## Ⅶ. 결론

- 작은 메모리와 엄격한 제어 주기가 요구되면 MCU와 실시간 커널을, 파일 시스템·네트워크 스택이 필요하면 MPU와 범용 OS를 선택하고, 신호처리·병렬 I/O가 지배적이면 DSP·FPGA를 보조로 두되 안전 기능만은 독립 감시 경로로 분리

#### 한줄 요약
- 임베디드 설계의 최종 판단 기준은 제품이 얼마나 잘 도느냐가 아니라 고장 났을 때 어떻게 멈추느냐이며, 안전 경로를 주 경로에서 떼어 놓는 이유도 여기에 있다.
