## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **주문형 반도체(Application-Specific Integrated Circuit, ASIC)**: 특정 응용 목적만을 위해 하드웨어 회로를 고정 설계하여 제작한 전용 반도체.
- **NRE(Non-Recurring Engineering)**: 반도체 마스크 제작 및 초기 설계 단계에서 발생하는 1회성 개발 비용.

</details>

- 정의/개념: 신경망의 주요 연산과 데이터 경로를 고정 회로로 구현한 **AI 전용 ASIC** 구조
- 배경/필요성: 범용 프로세서는 명령 해석·스케줄링과 데이터 이동에 전력·면적을 사용해 반복 행렬 연산 효율 제약

#### 한줄 요약
- 반복되는 AI 연산을 고정 회로로 만들어 범용 제어 비용을 줄인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스톨릭 어레이(Systolic Array)**: 데이터가 심장 박동처럼 격자형 연산기들을 통과하며 매트릭스 곱셈을 수행하는 구조.
- **TOPS/W**: 전력 1와트당 처리할 수 있는 조 단위 연산 횟수를 나타내는 반도체 전력 효율성 지표.

</details>

- **시스톨릭 어레이(Systolic Array)** 로 메모리 접근 최소화 및 2D MAC 가속
- 범용 제어 로직 축소로 높은 **와트당 성능(TOPS/W)** 확보
- 대량 생산 시 칩당 단가 절감 및 엣지/데이터센터 최적화

#### 한줄 요약
- 메모리 접근을 줄이는 시스톨릭 구조와 전용 회로로 전력 효율과 연산 처리량을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **텐서 처리 장치(TPU)**: 대규모 행렬 곱셈을 초고속으로 처리하기 위해 구글이 설계한 대표적인 AI 전용 ASIC.
- **활성화 함수 유닛(Vector Unit)**: ReLU, GELU, Softmax 등 비선형 활성화 함수를 고속 벡터 연산으로 처리하는 회로.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ AI 가속 ASIC 내부 아키텍처                                 │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 호스트 인터페이스 & 텐서 DMA (PCIe Gen5 / CXL)        │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │                               │
│  ┌──────────────────────────┴────────────────────────────┐  │
│  │ 온칩 가중치 & 활성화 SRAM 버퍼 (Unified Buffer)       │  │
│  └───────────┬───────────────────────────┬───────────────┘  │
│              │ (가중치 로드)             │ (입력 데이터)    │
│              │                           │                  │
│  ┌───────────────────────┐   ┌───────────────────────┐      │
│  │ 2D 시스톨릭 어레이    │───│ 벡터 활성화 연산 유닛 │      │
│  │ (Matrix Multiply Unit)│   │ (ReLU/GELU/Softmax)   │      │
│  └───────────────────────┘   └───────────┬───────────┘      │
│                                          │                  │
│  ┌───────────────────────────────────────┴───────────────┐  │
│  │ 외부 고대역폭 메모리 인터페이스 (HBM3 / LPDDR5X)      │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: DMA·SRAM·시스톨릭 어레이·벡터 유닛·외부 메모리 사이의 정적 연결

| 구성요소 | 책임 |
|:---|:---|
| 시스톨릭 어레이 매트릭스 | 2차원 격자 연산기로 행렬 곱셈(GEMM) 병렬 수행 |
| 온칩 통합 SRAM 버퍼 | 재사용할 가중치와 중간 텐서를 보관해 DRAM 접근 감소 |
| 벡터 활성화 엔진 | 비선형 활성화 함수(GELU, LayerNorm) 및 풀링 연산 전담 |
| 텐서 DMA 제어기 | 호스트 메모리 및 HBM과 온칩 SRAM 간 고속 블록 데이터 이동 |
| 고대역폭 메모리 (HBM) | 대규모 가중치와 텐서에 필요한 메모리 대역폭 공급 |

#### 한줄 요약
- 시스톨릭 어레이, 대용량 온칩 버퍼, 벡터 유닛, HBM 인터페이스가 유기적으로 맞물려 작동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가중치 고정(Weight-Stationary)**: 가중치를 연산기 셀 내부에 고정해 두고 입력 데이터를 흘려보내 누적하는 데이터 흐름 방식.

</details>

```text
호스트 AI 연산 명령 도달
      │
      ▼
1. 가중치 적재
      │
      ▼
2. 어레이 초기화
      │
      ▼
3. 입력 데이터 주입
      │
      ▼
4. 시스톨릭 누산
      │
      ▼
5. 활성화 연산
      │
      ▼
결과 텐서 반환
```

**동작 원리**

1. **가중치 적재**: HBM에서 모델 가중치를 읽어 온칩 고속 SRAM 버퍼에 사전 적재
2. **어레이 초기화**: 시스톨릭 어레이의 각 MAC 연산 셀 레지스터에 가중치 매트릭스 고정
3. **입력 데이터 주입**: 입력 피처맵 데이터를 행/열 단위로 시차를 두어 어레이로 주입
4. **시스톨릭 누산**: 데이터가 오른쪽과 아래로 이동하면서 곱셈과 덧셈을 한 클록마다 동시에 누적
5. **활성화 연산**: 최종 출력 행렬에 벡터 유닛이 활성화 함수 적용

#### 한줄 요약
- 가중치 버퍼 적재 → 시스톨릭 격자 주입 → 2D MAC 누산 → 활성화 함수 처리 후 완료된다.

## Ⅴ. 종류 및 비교

| AI 반도체 구조 | ASIC (TPU/NPU) | FPGA | GPU | 범용 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초대규모 양산·최대 전력 효율 요구 | 알고리즘 변경 잦음·초저지연 엣지 | 범용 대규모 딥러닝 학습/추론 | 범용 연산 및 복잡한 제어 흐름 |
| 핵심 특징 | AI 전용 하드웨어 고정 회로 집적 | 비트스트림 기반 회로 재구성 가능 | 수천 개 코어 기반 범용 병렬 처리 | 순차 명령어 고속 처리 및 큰 캐시 |
| 한계 | 설계 변경 불가·초기 NRE 비용 막대 | 클록 주파수 한계·개발 난이도 높음 | 높은 소비 전력 및 발열 관리 부담 | 대규모 행렬 병렬 연산 성능 부족 |

#### 한줄 요약
- 최고의 효율과 양산은 ASIC, 유연성과 저지연은 FPGA, 범용 병렬성은 GPU를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NRE 회수(NRE Amortization)**: 초기 마스크 제작 비용을 대량 생산을 통한 칩당 단가 절감으로 상쇄하는 전략.
- **소프트웨어 스택(Compiler/SDK)**: PyTorch/TensorFlow 코드를 ASIC 전용 어셈블리로 최적화 컴파일하는 도구 체계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 큰 초기 **NRE 비용**과 수요 예측 위험 | 양산량·제품 수명 검증 후 검증된 칩렛 IP 활용 | 칩당 고정비와 재설계 범위 축소 |
| 새로운 딥러닝 연산자 등장 시 지원 불가 | 프로그래머블 벡터 코어 및 VLIW 연산기 유연 결합 | 알고리즘 진화 대응 및 수명 주기 연장 |
| 전용 하드웨어용 컴파일러 생태계 미비 | OpenXLA, TVM 등 표준 오픈소스 컴파일러 프레임워크 연동 | 프레임워크 호환성 및 개발 생산성 확보 |
| 좁은 면적에 연산기 밀집으로 인한 고열 발생 | 전력 제한·열 해석 후 패키지와 냉각 방식 결정 | 스로틀링과 수명 저하 위험 완화 |

#### 한줄 요약
- 칩렛으로 NRE를 분산하고, 프로그래머블 유닛을 섞어 유연성을 챙기며, 오픈 컴파일러로 생태계를 구축한다.

## Ⅶ. 결론

- 연산 구조가 안정되고 양산량으로 **NRE**를 회수할 수 있으면 ASIC 선택
- 모델 변화가 잦거나 수요가 불확실하면 **GPU·FPGA**로 재설계 위험 축소

#### 한줄 요약
- ASIC은 최대 효율보다 제품 수명 동안의 NRE 회수 가능성을 먼저 판단해야 한다.
