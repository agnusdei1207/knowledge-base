## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 파이프라인에서 중첩 실행 중인 후속 명령어가 데이터 의존성, 분기 제어 흐름, 또는 하드웨어 자원 경합으로 인해 다음 사이클에 즉시 실행되지 못하는 상태.
- **파이프라인 스톨(Pipeline Stall)**: 해저드 요인이 해소될 때까지 특정 파이프라인 단계의 전진을 일시 동결하고 버블(NOP)을 삽입하는 하드웨어 제어 동작.
- **파이프라인 플러시(Pipeline Flush)**: 분기 오예측 또는 인터럽트 발생 시 파이프라인에 이미 인출된 잘못된 명령어들을 NOP으로 대체하여 무효화하는 제어 동작.

</details>

- 정의/개념: 중첩 실행 중인 명령어 간의 데이터 의존성(데이터), 분기 분기점 판정(제어), 하드웨어 자원 충돌(구조)로 인해 파이프라인 정상 전진이 방해받는 **파이프라인 해저드**
- 배경/필요성: 체계적인 해저드 감지 및 통제 회로 없이는 **오래된 레지스터 값 참조에 따른 연산 오류 및 잘못된 실행 경로 반영 불가피**

#### 한줄 요약
- 해저드는 파이프라이닝에서 발생하는 데이터 의존성, 분기 지연, 자원 충돌 현상이며, 포워딩, 예측, 자원 분리를 통해 통제한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 후속 명령어가 필요로 하는 피연산자 값이 선행 명령어의 레지스터 기록(WB) 전이라 아직 준비되지 않아 발생하는 충돌(RAW, WAR, WAW).
- **제어 해저드(Control Hazard)**: 조건부 분기 명령어의 분기 성립 여부 및 목표 주소가 계산되기 전까지 다음에 인출할 올바른 PC 주소를 확정하지 못해 발생하는 지연.
- **구조적 해저드(Structural Hazard)**: 복수의 파이프라인 단계가 동일한 물리적 하드웨어 자원(메모리 포트, ALU 등)을 동일 클록에 동시에 사용하려 할 때 발생하는 충돌.

</details>

- 데이터 해저드: **포워딩(Bypassing)** 또는 하드웨어 인터록 스톨을 통해 데이터 의존성을 보존하고 연산 무결성 보장
- 제어 해저드: **분기 예측** 및 오예측 플러시를 통해 인출 연속성을 유지하며 제어 지연 오버헤드 최소화
- 구조적 해저드: 명령어/데이터 메모리 분리(수정 하버드) 및 레지스터 파일의 **다중 포트(Multi-port)** 구성을 통해 하드웨어 자원 경합 제거

#### 한줄 요약
- 세 해저드는 각각 값 부족(데이터), 주소 미확정(제어), 자원 부족(구조)에 기인하며, 하드웨어 우회, 투기적 예측, 자원 복제를 통해 해결한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지 유닛(Hazard Detection Unit)**: ID 단계에서 후속 명령어의 소스 레지스터와 EX 단계의 로드 목적 레지스터를 비교하여 적재-사용 의존성 발생 시 스톨 신호를 발생시키는 회로.
- **포워딩 유닛(Forwarding Unit)**: EX/MEM 및 MEM/WB 파이프라인 레지스터의 목적 레지스터 번호와 현재 ID/EX 단계의 소스 레지스터 번호를 비교하여 우회 멀티플렉서를 제어하는 회로.
- **분기 판정 유닛(Branch Decision Unit)**: 분기 조건의 참/거짓을 평가하고 목표 주소를 계산하여 예측기와 대조하는 제어 회로.

</details>

```text
[파이프라인 해저드 통제 서브시스템]
 ├─ [데이터 해저드 제어]
 │   ├─ 포워딩 유닛 (EX/MEM, MEM/WB ➔ EX 입력 우회 제어)
 │   └─ 해저드 감지 유닛 (적재-사용 의존 감지 시 1사이클 스톨 신호 생성)
 │
 ├─ [제어 해저드 제어]
 │   ├─ 동적 분기 예측기 (BHT / BTB)
 │   └─ 분기 판정 및 플러시 제어기 (오예측 시 파이프라인 레지스터 NOP 소거)
 │
 └─ [구조적 해저드 제어]
     ├─ 분리 캐시 아키텍처 (L1 I-Cache vs L1 D-Cache)
     └─ 다중 포트 레지스터 파일 (2 Read Ports + 1 Write Port)
```

선의 의미: 가지(`├─`, `└─`)는 해저드 통제 회로의 소속 및 분류 관계; 각 유닛은 파이프라인 단계와 병렬로 상호작용함

| 해저드 유형 | 발생 원인 | 전담 통제 유닛 | 주요 해결 메커니즘 |
|:---|:---|:---|:---|
| **데이터 해저드** | RAW(Read-After-Write) 진성 의존성 | **포워딩 유닛**, 해저드 감지기 | ALU/MEM 결과 바이패스, Load-Use 1사이클 스톨 |
| **제어 해저드** | 분기 조건 판정 및 목표 주소 지연 | **분기 예측기**, 플러시 로직 | BHT/BTB 기반 투기 인출, 오예측 시 파이프라인 플러시 |
| **구조적 해저드** | 동일 클록 내 단일 자원 동시 접근 | **분리 캐시**, 다중 포트 회로 | I/D 캐시 분리(수정 하버드), 멀티포트 레지스터 파일 |

#### 한줄 요약
- 파이프라인은 데이터, 제어, 구조 해저드를 전담하는 하드웨어 감지 및 우회 회로를 내장하여 중첩 실행의 정합성을 보장한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 결과를 레지스터에 쓰기 전에 후속 명령어가 해당 레지스터를 읽으려 할 때 발생하는 진성 데이터 의존성.
- **적재-사용 의존(Load-Use Dependency)**: 메모리 로드 명령어의 데이터는 MEM 단계가 끝나야 확정되므로 EX 단계로 즉시 포워딩이 불가능하여 1사이클 스톨이 강제되는 상태.

</details>

```text
파이프라인 단계 진행 중 해저드 유형별 처리 흐름
 ├─ [ 1. 데이터 해저드 발생 (RAW 의존성) ]
 │    ├─ 선행 명령어가 ALU 연산인 경우 ──► 2. 포워딩 유닛이 EX 단계로 즉시 우회 (0 스톨)
 │    └─ 선행 명령어가 Load 연산인 경우 ──► 3. 해저드 감지기가 1사이클 스톨 삽입 후 MEM ➔ EX 포워딩
 │
 ├─ [ 2. 제어 해저드 발생 (조건부 분기) ]
 │    ├─ BHT/BTB 예측 방향과 일치 ──► 4. 파이프라인 중단 없이 연속 인출
 │    └─ 분기 오예측 판정 ──► 5. IF/ID 단계 플러시 및 올바른 목표 주소로 재인출
 │
 └─ [ 3. 구조적 해저드 발생 (자원 경합) ]
      ├─ I/D 캐시 분리 구조 ──► 6. 인출(IF)과 데이터 접근(MEM) 동시 처리
      └─ 단일 자원 경합 시 ──► 7. 하드웨어 중재기가 우선순위에 따라 1사이클 지연
```

분기 결과: **포워딩은** 스톨 없이 데이터를 즉시 공급하고, **적재-사용은** 1사이클 스톨을 거치며, **분기 오예측은** 플러시 페널티를 치르고 재인출함

#### 한줄 요약
- 세 가지 해저드는 포워딩 바이패스, 1사이클 스톨, 분기 예측 및 플러시를 통해 각각 최적화된 경로로 복구된다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 데이터 해저드 (Data Hazard) | 제어 해저드 (Control Hazard) | 구조적 해저드 (Structural Hazard) |
|:---|:---|:---|:---|
| 발생 원인 | **선행-후속 명령어 간 데이터(RAW) 의존성** | **분기 명령어로 인한 다음 PC 주소 미확정** | **동일 하드웨어 자원에 대한 동시 접근 경합** |
| 해결 하드웨어 | **포워딩 회로 및 해저드 감지 유닛** | **동적 분기 예측기(BHT/BTB) 및 플러시 회로** | **I/D 분리 캐시 및 다중 포트 레지스터** |
| 성능 영향 | 대부분 0~1사이클 지연으로 방어 | 오예측 시 파이프라인 깊이에 비례한 플러시 손실 | 자원 복제 시 지연 0, 미복제 시 스톨 발생 |
| 컴파일러 역할 | 명령어 스케줄링(Load 지연 슬롯 채우기) | 지연 분기(Delayed Branch) 슬롯 스케줄링 | 자원 사용 최적화 |

#### 한줄 요약
- 데이터 해저드는 우회 회로로, 제어 해저드는 예측기로, 구조적 해저드는 자원 분리를 통해 파이프라인 처리량 손실을 방어한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **지연 분기(Delayed Branch)**: 분기 명령어 직후의 1~2개 슬롯(Branch Delay Slot)에 분기 여부와 무관하게 항상 실행될 유효 명령어를 컴파일러가 배치하는 기법.
- **비순서 실행(Out-of-Order Execution, OoO)**: 데이터 의존성이 없는 후속 명령어를 먼저 실행 유닛에 투입하여 스톨 구간을 유용한 연산으로 채우는 고급 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적재-사용 의존으로 인한 1사이클 스톨 반복 발생 | **컴파일러 명령어 스케줄링** 및 **비순서 실행(OoO)** 적용 | 스톨 슬롯에 독립 명령어를 배치하여 유휴 시간 은닉 |
| 깊은 파이프라인에서 분기 오예측 플러시 페널티 급증 | **2단계 적응형 분기 예측기(TAGE 등)** 및 조기 분기 판정 | 분기 예측 정확도 95% 이상 달성 및 플러시 최소화 |
| 메모리 포트 부족으로 인한 구조적 경합 | **L1 캐시 I/D 분리(수정 하버드)** 및 듀얼 포트 SRAM 채택 | 명령어 인출과 데이터 메모리 접근의 동시 병렬성 보장 |

#### 한줄 요약
- 해저드 실무 대책은 컴파일러 스케줄링과 비순서 실행, TAGE 고정밀 분기 예측기, 분리 캐시 아키텍처의 통합 적용으로 완성된다.

## Ⅶ. 결론

- 파이프라인 중첩 실행의 효율을 보장하기 위해 **데이터 해저드는 하드웨어 포워딩과 스케줄링**, **제어 해저드는 동적 분기 예측과 플러시 메커니즘**, **구조적 해저드는 수정 하버드 L1 I/D 분리 캐시**를 체계적으로 구축하여 사이클당 명령어 처리율(IPC)을 극대화하는 프로세서 아키텍처 확립

#### 한줄 요약
- 파이프라인 해저드 통제는 하드웨어 우회 회로와 컴파일러 최적화가 유기적으로 맞물려야 이상적인 고성능을 달성할 수 있다.
