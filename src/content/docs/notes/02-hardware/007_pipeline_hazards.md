## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 파이프라인에서 중첩 실행 중인 후속 명령어가 데이터 의존성, 분기 제어 흐름, 또는 하드웨어 자원 경합으로 인해 다음 사이클에 즉시 실행되지 못하는 상태.
- **파이프라인 스톨(Pipeline Stall)**: 해저드 요인이 해소될 때까지 특정 파이프라인 단계의 전진을 일시 동결하고 버블(NOP)을 삽입하는 하드웨어 제어 동작.
- **파이프라인 플러시(Pipeline Flush)**: 분기 오예측 또는 인터럽트 발생 시 파이프라인에 이미 인출된 잘못된 명령어들을 NOP으로 대체하여 무효화하는 제어 동작.

</details>

- 정의/개념: 파이프라인에서 중첩 실행 중인 후속 명령어가 데이터 의존성, 분기 조건 미확정, 하드웨어 자원 충돌로 인해 차기 클록에 실행되지 못하고 지연되는 **파이프라인 장애 현상**
- 배경/필요성: 명령어 간 연산 의존성 및 제어 흐름 분기로 인해 파이프라인 정지(Stall)와 오연산이 발생하므로 스톨을 최소화하고 실행 무결성을 보장하기 위한 하드웨어 우회 및 투기적 실행 회로 필수화

#### 한줄 요약
- 해저드는 파이프라이닝에서 발생하는 데이터 의존성, 분기 지연, 자원 충돌 현상이며, 포워딩, 예측, 자원 분리를 통해 통제한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 후속 명령어가 필요로 하는 피연산자 값이 선행 명령어의 레지스터 기록(WB) 전이라 아직 준비되지 않아 발생하는 충돌(RAW, WAR, WAW).
- **제어 해저드(Control Hazard)**: 조건부 분기 명령어의 분기 성립 여부 및 목표 주소가 계산되기 전까지 다음에 인출할 올바른 PC 주소를 확정하지 못해 발생하는 지연.
- **구조적 해저드(Structural Hazard)**: 복수의 파이프라인 단계가 동일한 물리적 하드웨어 자원(메모리 포트, ALU 등)을 동일 클록에 동시에 사용하려 할 때 발생하는 충돌.

</details>

- **데이터 해저드**: 포워딩(Bypassing) 또는 하드웨어 인터록 스톨을 통해 데이터 의존성을 보존하고 연산 무결성 보장
- **제어 해저드**: 분기 예측 및 오예측 플러시를 통해 인출 연속성을 유지하며 제어 지연 오버헤드 최소화
- **구조적 해저드**: 명령어/데이터 메모리 분리(수정 하버드) 및 레지스터 파일의 다중 포트 구성을 통해 하드웨어 자원 경합 제거

#### 한줄 요약
- 세 해저드는 각각 값 부족(데이터), 주소 미확정(제어), 자원 부족(구조)에 기인하며, 하드웨어 우회, 투기적 예측, 자원 복제를 통해 해결한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지 유닛(Hazard Detection Unit)**: ID 단계에서 후속 명령어의 소스 레지스터와 EX 단계의 로드 목적 레지스터를 비교하여 적재-사용 의존성 발생 시 스톨 신호를 발생시키는 회로.
- **포워딩 유닛(Forwarding Unit)**: EX/MEM 및 MEM/WB 파이프라인 레지스터의 목적 레지스터 번호와 현재 ID/EX 단계의 소스 레지스터 번호를 비교하여 우회 멀티플렉서를 제어하는 회로.
- **분기 판정 유닛(Branch Decision Unit)**: 분기 조건의 참/거짓을 평가하고 목표 주소를 계산하여 예측기와 대조하는 제어 회로.

</details>

```text
+-----------------------------------------------------------------------+
| 파이프라인 해저드 통제 하드웨어 아키텍처                              |
|  +-----------------------------------------------------------------+  |
|  | 파이프라인 데이터패스 (IF - ID - EX - MEM - WB)                  |  |
|  |                                                                 |  |
|  |  +---------------+    포워딩 바이패스 버스   +---------------+  |  |
|  |  | EX 단계 (ALU) |<=========================| MEM/WB 단계   |  |  |
|  |  +-------^-------+                          +---------------+  |  |
|  |          |                                                     |  |
|  +----------|-----------------------------------------------------+  |
|             | 제어 신호                                               |
|  +----------v------------------------------------------------------+  |
|  | 해저드 제어 회로 블록                                           |  |
|  |  - 포워딩 유닛: 레지스터 주소 비교 및 EX 단계 바이패스 MUX 제어 |  |
|  |  - 해저드 감지 유닛: 로드-사용 의존 검출 및 파이프라인 스톨 주입|  |
|  |  - 분기 제어 유닛: BTB/BHT 예측 실패 시 파이프라인 플러시 발생 |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

선의 의미: `+---+`는 데이터패스 및 해저드 제어 유닛 경계, `<==`는 바이패스 데이터 경로, `->`는 스톨/플러시 제어 신호 흐름

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 유닛 | 파이프라인 레지스터의 목적 주소 비교 및 연산 입력 **우회 바이패스** 제어 |
| 해저드 감지 유닛 | 적재-사용(Load-Use) 의존 검출 시 1사이클 **스톨 버블 삽입** 지시 |
| 분기 판정 유닛 | 분기 조건 성립 여부 조기 판정 및 오예측 시 **파이프라인 플러시** 수행 |
| 분리 캐시·다중 포트 | 명령어/데이터 캐시 분리 및 다중 포트 레지스터를 통한 **자원 경합 차단** |

#### 한줄 요약
- 파이프라인은 데이터, 제어, 구조 해저드를 전담하는 하드웨어 감지 및 우회 회로를 내장하여 중첩 실행의 정합성을 보장한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 결과를 레지스터에 쓰기 전에 후속 명령어가 해당 레지스터를 읽으려 할 때 발생하는 진성 데이터 의존성.
- **적재-사용 의존(Load-Use Dependency)**: 로드 결과 준비 전에 후속 명령어가 값을 요구하여 포워딩만으로 해소되지 않을 수 있는 RAW 의존성.

</details>

```text
[파이프라인 명령어 중첩 실행 단계 진입]
                   │
                   ▼
       1. 해저드 유형 및 발생 조건 판정
   ┌───────────────┼──────────────────┐
(RAW 데이터 충돌) (분기 오예측 확정)   (하드웨어 자원 충돌)
   │               │                  │
   ▼               ▼                  ▼
2. 포워딩·스톨   3. 플러시·재인출   4. 자원 분리·중재
(우회 또는 버블) (무효화 후 복구)   (포트 분리 접근)
   │               │                  │
   └───────────────┼──────────────────┘
                   │
                   ▼
[정합성 복구 후 유효 명령어 파이프라인 전진 지속]
```

분기 결과: **RAW**는 결과 준비 시점에 따라 우회 또는 1사이클 **파이프라인 스톨**을 치르고, 분기 오예측은 이미 진입한 명령어를 **파이프라인 플러시**로 전부 폐기한 뒤 재인출하며, 자원 경합은 분리된 자원으로 동시 접근하거나 우선순위로 지연됨

**동작 원리**

1. **해저드 유형 및 발생 조건 판정**: 매 사이클 ID 단계에서 피연산자 준비 상태, 분기 명령어 여부, 하드웨어 포트 가용성을 종합 평가함
2. **포워딩·스톨**: RAW 데이터 의존성 검출 시 직전 연산 결과를 EX 입력으로 바이패스하며, 로드-사용 의존성의 경우 1사이클 스톨 버블을 삽입함
3. **플러시·재인출**: EX 단계에서 분기 오예측 확정 시 이미 IF/ID 단계에 인출된 무효 명령어를 플러시하고 정정된 주소로 재인출을 지시함
4. **자원 분리·중재**: 하드웨어 포트 충돌 발생 시 중재 로직에 따라 우선순위 단계를 먼저 실행하고 후순위 단계에 임시 대기를 명령함

#### 한줄 요약
- 해저드 대응은 스톨로 정확성만 지킬지, 포워딩·예측 회로를 더 실어 처리량까지 지킬지의 선택이며, 자원 해저드만은 유닛 복제라는 면적 비용으로만 풀린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **지연 분기(Delayed Branch)**: 분기 명령어 직후의 1~2개 슬롯(Branch Delay Slot)에 분기 여부와 무관하게 항상 실행될 유효 명령어를 컴파일러가 배치하여 분기 판정 대기 사이클을 유용한 연산으로 채우는 기법.

</details>

| 파이프라인 해저드 | 데이터 해저드 | 제어 해저드 | 구조적 해저드 |
|:---|:---|:---|:---|
| 적용 기준 | **연산 결과 피연산자 참조** 발생 시 | **조건부 분기 및 점프 명령** 실행 시 | **복수 단계의 동일 하드웨어 경합** 시 |
| 핵심 특징 | RAW/WAR/WAW 의존성에 의한 데이터 충돌 | 분기 목표 주소 미확정으로 인한 경로 단절 | 물리적 메모리 포트 및 연산기 수량 부족 |
| 한계 | 로드 명령어 직후 무조건 1스톨 발생 | 오예측 시 파이프라인 깊이에 비례한 플러시 손실 | 하드웨어 유닛 복제에 따른 칩 면적 비용 증가 |

#### 한줄 요약
- 데이터 해저드는 우회 회로로, 제어 해저드는 예측기로, 구조적 해저드는 자원 분리를 통해 파이프라인 처리량 손실을 방어한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비순서 실행(Out-of-Order Execution, OoO)**: 데이터 의존성이 없는 후속 명령어를 먼저 실행 유닛에 투입하여 스톨 구간을 유용한 연산으로 채우는 고급 기법.
- **TAGE(TAgged GEometric history length predictor)**: 길이가 기하급수적으로 늘어나는 여러 전역 분기 이력 테이블을 태그로 병렬 조회하고, 가장 긴 이력이 일치한 테이블의 예측을 채택하여 상관관계가 먼 분기까지 적중률을 높이는 동적 분기 예측기.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적재-사용 의존으로 인한 1사이클 스톨 반복 발생 | 컴파일러 명령어 재배치 및 **비순서 실행(OoO)** 적용 | 스톨 구간에 무관한 독립 명령어를 채워 IPC 손실 은닉 |
| 깊은 파이프라인에서 분기 오예측 시 플러시 페널티 급증 | **TAGE 예측기** 도입 및 분기 조기 판정 회로 구성 | 분기 예측 적중률 97% 이상 달성 및 파이프라인 낭비 최소화 |
| 명령어 인출과 데이터 로드의 단일 메모리 포트 경합 | L1 I/D **분리 캐시** 및 듀얼 포트 SRAM 채택 | 하드웨어 자원 충돌 완전 해소 및 매 클록 동시 접근 보장 |

#### 한줄 요약
- 해저드 실무 대책은 컴파일러 스케줄링과 비순서 실행, TAGE 고정밀 분기 예측기, 분리 캐시 아키텍처의 통합 적용으로 완성된다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차적으로 완료된 연산 결과들을 원래의 프로그램 순서대로 대기시켰다가 커밋하여 예외 정합성을 보장하는 순환 큐 버퍼.
- **칩렛(Chiplet)**: 대형 모놀리식 다이를 기능별 단위 다이로 분할 제조한 후 고속 인터커넥트로 통합 패키징하는 반도체 구조.

</details>

- 포워딩 회로·정밀 분기 예측기(TAGE)·하버드 캐시 분리가 결합된 해저드 방어 체계가 현대 프로세서의 표준으로 안착하였으며, 차세대 마이크로아키텍처에서는 대규모 **ROB** 기반 **비순서 실행(OoO)**과 **칩렛** 인터커넥트 중재 구조로 진화하고 있어, 회로 면적·전력 예산과 해저드 완화율 간 트레이드오프를 평가한 바이패스 경로 수·큐 깊이 설계

#### 한줄 요약
- 파이프라인 해저드 통제는 하드웨어 우회 회로와 컴파일러 최적화가 유기적으로 맞물려야 이상적인 고성능을 달성할 수 있다.
