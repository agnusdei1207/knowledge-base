## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 명령어를 단계별로 중첩 실행할 때 의존성•분기•자원 경합이 정상 진행을 방해하는 조건이다.
- **스톨(Stall)**: 해저드가 해소될 때까지 일부 파이프라인 단계의 진행을 멈추는 제어 방식이다.
- **포워딩(Forwarding)**: 연산 결과를 레지스터에 기록하기 전에 의존 명령의 입력으로 직접 전달하는 제어 방식이다.
- **플러시(Flush)**: 잘못 인출한 명령을 무효화하고 올바른 경로에서 실행을 다시 시작하는 제어 방식이다.

</details>

- 정의/개념: **파이프라인 해저드**는 명령 중첩 시 데이터 의존•분기•자원 경합이 정상 실행을 방해하는 조건이다.
- 배경/필요성: 해저드를 제어하지 않으면 잘못된 피연산자나 분기 경로를 실행할 수 있어 **포워딩**•**스톨**•**플러시**가 필요하다.

#### 한줄 요약
- Instruction Pipelining 시 발생하는 Structural/Data/Control Hazard를 Hazard Detection Unit과 Control Logic을 통해 즉각 감지 및 해소해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **명령어당 사이클 수(Cycles Per Instruction, CPI)**: 명령어 하나를 완료하는 데 필요한 평균 클록 수이다.
- **버블(Bubble)**: 스톨이나 플러시로 파이프라인 단계에 유효한 명령이 없는 상태이다.
- **명령 처리량**: 단위 시간에 완료하는 명령어 수이다.

</details>

- 같은 진행 방해라도 원인에 따라 **포워딩**•**플러시**•자원 중재 등 필요한 대책이 다르다.
- 스톨•플러시로 **버블**이 늘어나면 **명령 처리량**이 감소한다.
- 해저드 발생 빈도와 해소에 필요한 지연 클록 수가 **CPI** 상승 폭을 결정한다.

#### 한줄 요약
- Hazard 발생 빈도와 Stall Cycle / Flush Penalty가 누적됨에 따라 Ideal CPI(1.0)에 추가적인 CPI Overhead가 가산된다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **해저드 감지기(Hazard Detection Unit)**: 파이프라인 레지스터의 원천•목적 레지스터와 자원 사용을 비교해 충돌을 판정한다.
- **포워딩 경로(Forwarding Path)**: 앞 명령의 결과를 후속 명령의 실행 입력으로 우회 전달하는 데이터 경로이다.
- **자원 중재기(Resource Arbiter)**: 같은 하드웨어 자원을 동시에 요구하는 명령의 사용 순서를 정한다.
- **분기 제어기(Branch Control Unit)**: 예측과 실제 분기 결과를 비교해 다음 인출 주소와 플러시를 결정한다.
- **파이프라인 레지스터**: 단계별 명령•피연산자•제어 상태를 클록 경계에서 보관하는 레지스터이다.

</details>

```text
파이프라인 해저드 제어
├─ 파이프라인 레지스터
├─ 해저드 감지기
├─ 포워딩 경로
├─ 분기 제어기
└─ 자원 중재기
```

가지의 의미: 파이프라인 레지스터가 단계별 상태를 제공하고, 감지기와 각 제어 회로가 해저드를 판정하고 원인별 대책을 적용하는 구성을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **파이프라인 레지스터** | 단계별 명령•피연산자•제어 상태 보관 |
| **해저드 감지기** | 레지스터 의존성과 자원 충돌 판정 |
| **포워딩 경로** | 결과를 후속 명령의 실행 입력으로 우회 |
| **분기 제어기** | 예측 검증과 인출 주소•플러시 결정 |
| **자원 중재기** | 공유 자원의 사용 순서•스톨 결정 |

#### 한줄 요약
- Hazard Detection Unit이 Register Dependency 및 Resource Contention을 디코딩하고, Forwarding Unit, Branch Control Unit, Resource Arbiter가 수습 제어를 담당한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **원천 레지스터(Source Register)**: 명령어가 피연산자를 읽는 레지스터이다.
- **목적 레지스터(Destination Register)**: 명령어가 결과를 기록하는 레지스터이다.
- **완화 제어 신호**: 해저드 유형에 맞춰 포워딩•스톨•플러시•중재 동작을 지정하는 신호이다.
- **해저드 탐지**: 원천•목적 레지스터와 분기 결과•자원 요구를 비교해 충돌을 찾는 단계이다.
- **완화 방식 선택**: 해저드 원인에 맞춰 포워딩•스톨•플러시•중재 중 적용 동작을 정하는 단계이다.
- **파이프라인 상태 갱신**: 완화 제어 신호를 파이프라인 레지스터와 다음 인출 주소에 반영하는 단계이다.

</details>

```text
파이프라인 단계 상태
          │
          ▼
1. 해저드 탐지
          │
          ▼
2. 완화 방식 선택
          ├─ 데이터: 포워딩 또는 스톨
          ├─ 제어  : 예측 검증 또는 플러시
          └─ 구조  : 자원 중재 또는 스톨
          │
          ▼
3. 파이프라인 상태 갱신
          │
          ▼
      정상 실행 재개
```

### 동작 원리

1. **해저드 탐지**: **원천 레지스터**•**목적 레지스터**, 분기 결과, 자원 요구를 비교한다.
2. **완화 방식 선택**: 원인별 포워딩•스톨•플러시•중재를 결정한다.
3. **파이프라인 상태 갱신**: **완화 제어 신호**로 다음 입력과 단계 진행 여부를 확정한다.

#### 한줄 요약
- Hazard Detection $\rightarrow$ Mitigation Strategy Selection(Forwarding / Stall / Flush / Arbitration) $\rightarrow$ Control Signal Assembly 및 State Update 순서로 처리된다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 해저드(Data Hazard)**: 명령 간 데이터 의존으로 읽기•쓰기 순서가 충돌하는 해저드이다.
- **제어 해저드(Control Hazard)**: 분기 방향과 대상 주소가 확정되기 전에 후속 명령을 인출해 발생하는 해저드이다.
- **구조적 해저드(Structural Hazard)**: 여러 명령이 같은 하드웨어 자원을 같은 클록에 요구해 발생하는 해저드이다.
- **쓰기 후 읽기(Read After Write, RAW)**: 앞 명령의 기록 전에 뒤 명령이 같은 위치를 읽는 의존이다.
- **추측 인출(Speculative Fetch)**: 분기 결과가 확정되기 전에 예측 경로의 명령을 인출하는 동작이다.
- **자원 복제(Resource Duplication)**: 동시에 요구되는 포트나 연산기를 추가해 구조적 해저드를 줄이는 방법이다.
- **분기 예측(Branch Prediction)**: 분기 결과가 확정되기 전에 방향과 대상 주소를 추정해 후속 명령을 인출하는 기법이다.

</details>

| 파이프라인 해저드 | 데이터 해저드 | 제어 해저드 | 구조적 해저드 |
|:---|:---|:---|:---|
| 발생 조건 | 후행 명령이 미완료 선행 결과 참조 | **추측 인출** 중 분기 방향•대상 확정 전 실행 | 같은 클록에 동일 포트•연산기 요구 |
| 대표 충돌 | **RAW** 의존으로 피연산자 준비 지연 | 예측 경로 오류로 후속 명령 무효화 | 단일 자원 요청의 동시 경합 |
| 주요 완화 | **포워딩**•**스톨** | **분기 예측**•**플러시** | **자원 복제**•자원 중재 |

> 요약: 원인별 **포워딩**•**분기 예측**•**자원 복제**를 적용한다.

#### 한줄 요약
- Data Hazard는 Bypass/Forwarding/Stall, Control Hazard는 Branch Predictor/Flush, Structural Hazard는 Resource Duplication/Arbiter로 완화한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **적재-사용 의존(Load-Use Dependency)**: 메모리 적재값이 준비되기 전에 후속 명령이 이를 요구해 포워딩 후에도 스톨이 남는 의존이다.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 이전 분기의 주소와 대상을 저장해 다음 인출 주소 예측을 돕는 하드웨어이다.
- **명령 스케줄링(Instruction Scheduling)**: 의존성이 없는 명령을 대기 구간에 배치해 스톨을 줄이는 기법이다.
- **분기 예측기(Branch Predictor)**: 과거 분기 이력으로 분기 방향을 확정 전에 추정하는 하드웨어이다.
- **다중 포트**: 자원에 동시에 접근할 수 있도록 복수 통로를 제공하는 구조이다.
- **중재 정책**: 동시 자원 요청의 처리 순서를 정하는 규칙이다.
- **적재 지연 은닉(Load Latency Hiding)**: 적재값을 기다리는 동안 독립 명령을 실행해 적재 대기와 유효 연산을 겹치고 체감 스톨을 줄이는 기법이다.
- **조기 판정**: 분기 조건과 대상 주소를 앞 단계에서 확정해 잘못 인출하는 명령 수를 줄이는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **RAW** 의존 시 레지스터 기록까지 대기 | **포워딩**•**명령 스케줄링** 적용 | 데이터 스톨 감소 |
| **적재-사용 의존**에서 포워딩 후에도 버블 잔존 | **해저드 감지기**와 **명령 스케줄링** 적용 | **적재 지연 은닉** |
| 분기 오예측•플러시 증가 | **분기 예측기**•**BTB**•**조기 판정** 개선 | 제어 해저드 비용 감소 |
| 단일 포트•연산기 경합 증가 | **자원 복제**•**다중 포트**•**중재 정책** 적용 | **구조적 해저드** 감소 |

#### 한줄 요약
- Load-Use Hazard 시 1-cycle Stall 및 Code Reordering(Scheduling)을 적용하고, Control Hazard 시 BTB/Dynamic Predictor, Structural Hazard 시 Multi-port RAM/Duplication 기법을 배정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **면적•전력 비용**: 포워딩•예측•자원 복제 회로를 추가하면서 늘어나는 칩 공간과 에너지 소비이다.
- **추가 CPI**: 해저드의 스톨•플러시로 기준 실행보다 늘어난 명령어당 평균 클록 수이다.
- **완화 회로 선택 기준**: 해저드별 추가 CPI 감소량과 면적•전력 비용을 함께 비교하는 기준이다.

</details>

- **완화 회로 선택 기준**에 따라 해저드별 **추가 CPI**와 **면적•전력 비용**을 비교해 포워딩•예측•자원 복제를 선택한다.

#### 한줄 요약
- Hazard Mitigation Unit 설계 시 $\Delta \text{CPI}$ 감소 폭과 Area/Power Overhead trade-off를 정밀 계측하여 하드웨어 자원을 할당한다.
