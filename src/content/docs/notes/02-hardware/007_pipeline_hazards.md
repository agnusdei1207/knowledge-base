## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 파이프라인에서 중첩 실행 중인 다음 명령어가 데이터 의존성, 분기 제어 흐름, 하드웨어 자원 충돌 등으로 인해 제 사이클에 실행되지 못하는 상태.
- **스톨(Stall)**: 해저드가 해소될 때까지 특정 파이프라인 단계의 전진을 지연시키고 버블(NOP)을 삽입하는 하드웨어 제어 동작.
- **플러시(Flush)**: 분기 오예측 또는 인터럽트 발생 시 파이프라인에 이미 인출된 잘못된 명령어들을 NOP으로 대체하여 취소하는 복구 동작.

</details>

- 정의/개념: 중첩 실행 중인 명령어들이 값·다음 주소·하드웨어 자원을 두고 충돌해 정상 진행이 막히는 **파이프라인 해저드**
- 배경/필요성: 해저드 제어 없이는 **오래된 피연산자 참조 및 잘못된 실행 경로 반영 불가피**

#### 한줄 요약
- 해저드는 파이프라이닝의 부작용이 아니라 중첩 실행이 성립하기 위해 반드시 지불해야 하는 대가이며, 없앨 수는 없고 값싸게 처리할 수만 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어의 연산 결과를 레지스터 기록(WB) 전에 후속 명령어의 실행(EX) 단계 입력으로 직접 전달하는 우회(Bypassing) 회로 기법.
- **분기 예측(Branch Prediction)**: 조건부 분기의 실행 결과가 확정되기 전에 분기 성립 여부 및 목표 주소를 미리 추측하여 파이프라인 인출을 중단 없이 지속하는 기법.
- **버블(Bubble)**: 스톨 제어에 의해 파이프라인 레지스터에 삽입되는 무효 연산(NOP) 슬롯으로, 유효한 작업 없이 파이프라인을 통과하는 빈 사이클.

</details>

- 데이터 해저드: **포워딩** 또는 스톨을 통한 의존성 해결로 잘못된 피연산자 참조 방지
- 제어 해저드: **분기 예측** 및 오예측 플러시로 인출 연속성 유지와 잘못된 경로 폐기
- 구조 해저드: 자원 분리·다중 포트·중재로 동시 자원 요청에 따른 **스톨** 방지

#### 한줄 요약
- 세 해저드는 각각 값·주소·자원이 부족해 생기므로, 대책도 값을 앞당기거나 주소를 추측하거나 자원을 늘리는 셋으로 갈린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지기(Hazard Detection Unit)**: 파이프라인 레지스터에 보관된 소스/목적 레지스터 번호와 메모리 읽기/쓰기 제어 신호를 비교하여 충돌을 감지하고 스톨 신호를 생성하는 회로.
- **분기 제어기(Branch Control Unit)**: 실행(EX) 단계의 분기 비교 결과와 예측 결과를 대조하여 분기 오예측 시 PC 복구 및 플러시 제어 신호를 발생하는 회로.
- **자원 중재기(Resource Arbiter)**: 단일 메모리 포트나 기능 유닛 등에 동시 접근 요청이 발생할 때 우선순위에 따라 접근 권한을 할당하는 하드웨어 중재 회로.

</details>

```text
[파이프라인 해저드 제어]
├─ 해저드 감지기  (레지스터 의존성·자원 충돌 판정)
├─ 포워딩 경로   (EX/MEM·MEM/WB → EX 단계 우회)
├─ 분기 제어기   (예측 비교·PC 복구·플러시)
└─ 자원 중재기   (공유 메모리·실행 유닛 접근 순서)
```

선의 의미: 가지(`├─`)는 해저드 제어 서브시스템의 소유 관계; 각 구성요소는 파이프라인 단계와 병렬로 동작

| 구성요소 | 책임 |
|:---|:---|
| 해저드 감지기 | 데이터 의존성과 자원 충돌 판정·**스톨** 신호 발생 |
| 포워딩 경로 | 준비된 ALU·메모리 결과를 EX 단계로 직접 우회 |
| 분기 제어기 | 오예측 확인 후 PC 복구와 **플러시** 제어 |
| 자원 중재기 | 공유 자원 동시 요청 조정으로 구조 해저드 해소 |

#### 한줄 요약
- 감지 회로는 파이프라인 밖에 있지만 판정이 한 클록 안에 끝나야 하므로, 해저드 제어의 실제 제약은 논리 복잡도가 아니라 판정 속도다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 레지스터에 값을 쓰기(Write) 전에 후속 명령어가 해당 레지스터를 읽으려(Read) 할 때 발생하는 진성 데이터 의존성(True Data Dependency).
- **적재-사용 의존(Load-Use Dependency)**: 메모리 로드 명령어의 결과가 MEM 단계를 거쳐야 확정되므로 즉시 EX 포워딩이 불가능하여 최소 1사이클의 스톨이 강제되는 특수 RAW 해저드.
- **적재 지연 은닉(Load-Use Latency Hiding)**: 컴파일러 또는 비순차 실행 엔진이 로드 명령어와 그 결과를 사용하는 명령어 사이에 독립적인 명령어를 재배치하여 로드 지연 스톨을 숨기는 최적화 기법.

</details>

```text
충돌 원인 판정
├─ 값 준비 미완료
│  ├─ 포워딩 가능 ─ 포워딩 경로 선택
│  └─ 포워딩 불가 ─ 스톨·버블 삽입
├─ 다음 PC 미확정
│  ├─ 예측 일치 ─── 계속 실행
│  └─ 예측 오류 ─── 플러시·PC 복구
└─ 공유 자원 경합
   ├─ 대체 자원 있음 ─ 분리 자원 배정
   └─ 대체 자원 없음 ─ 중재 후 대기
```

분기 결과: 값 부족은 우회로 대부분 해소되지만 주소 부족은 틀렸을 때만 대가를 치르고, 자원 부족은 회로를 늘리기 전까지 해소되지 않음

#### 한줄 요약
- 세 갈래 중 데이터와 제어는 설계로 완화할 수 있지만 구조 해저드만은 면적을 더 쓰는 것 말고 해법이 없어, 저면적 설계에서 가장 먼저 병목이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다중 포트(Multi-port)**: 레지스터 파일이나 메모리 등에 복수의 읽기/쓰기 포트를 독립적으로 구성하여 동시 접근에 의한 구조적 해저드를 방지하는 설계 방식.
- **인터록(Interlock)**: 데이터 의존성이 해소될 때까지 하드웨어가 파이프라인 진행을 자동으로 멈추고 제어 신호를 동결시키는 하드웨어 인터록 메커니즘.

</details>

| 해저드 유형 | 데이터 해저드 | 제어 해저드 | 구조 해저드 |
|:---|:---|:---|:---|
| 적용 기준 | **RAW** 의존성으로 값 준비 지연 | 분기·점프로 다음 PC 미확정 | 같은 자원의 동시 사용 요구 |
| 핵심 특징 | **포워딩** 또는 인터록으로 의존성 보존 | **분기 예측**·플러시·PC 복구 | 자원 분리·다중 포트·중재 |
| 한계 | 적재-사용 의존은 스톨 불가피 | 오예측 시 진행 명령어 플러시 비용 | 면적·전력·설계 복잡도 증가 |

#### 한줄 요약
- 구분 기준은 무엇이 부족한가이며, 부족한 것이 값이면 기다리면 오고 주소면 찍으면 되지만 자원은 기다려도 오지 않는다는 점이 결정적 차이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 명령어의 주소와 계산된 목표 주소를 캐싱하여 IF 단계에서 목표 주소로 즉시 분기할 수 있도록 지원하는 고속 캐시.
- **명령어 스케줄링(Instruction Scheduling)**: 컴파일러가 프로그램의 의미를 보존하면서 파이프라인 스톨을 최소화하도록 명령어의 실행 순서를 재배치하는 코드 최적화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **RAW** 의존성으로 결과 준비 전 사용 | **포워딩** 경로와 인터록 적용 | 오래된 값 사용 방지·스톨 최소화 |
| **적재-사용 의존** 기반 로드 결과 즉시 사용 불가 | 스톨 1사이클 삽입·**명령어 스케줄링** 기반 **적재 지연 은닉** | 유효 스톨 사이클 감소 |
| 분기 목표와 방향 불확실로 인출 중단 | **BTB**·분기 예측·오예측 시 플러시 | 인출 연속성·예측 성공률 향상 |
| 단일 메모리·실행 유닛에 동시 요청 집중 | 자원 분리·다중 포트 설계 | 구조 해저드 빈도 감소 |

#### 한줄 요약
- 네 대책 중 셋은 하드웨어를 더 쓰지만 **명령어 스케줄링**만은 컴파일 시점에 공짜로 얻으므로, 비용 대비 효과는 소프트웨어 쪽이 먼저다.

## Ⅶ. 결론

- 데이터는 **포워딩**, 제어는 **분기 예측**, 구조는 **자원 분리** 선택

#### 한줄 요약
- 해저드 대책은 많이 넣을수록 좋은 것이 아니라, 정확성을 지키는 인터록 위에 필요한 처리량만큼의 포워딩과 예측을 더하는 선택이다.
