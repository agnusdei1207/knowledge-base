## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 명령어 의존성, 조건 분기, 자원 충돌로 인해 다음 사이클 실행이 지연되는 현상.
- **스톨(Stall)**: 해저드가 해소될 때까지 파이프라인 특정 단계를 정지시키고 빈 버블(Bubble)을 주입하는 제어.
- **포워딩(Forwarding/Bypassing)**: 연산 결과를 레지스터 파일 기록 전에 다음 연산기 입력으로 직접 전달하는 하드웨어 기법.
- **플러시(Flush)**: 분기 예측 실패 시 이미 인출된 잘못된 명령어들을 파이프라인에서 폐기하는 동작.

</details>

- 정의/개념: 명령어 파이프라인 처리 과정에서 데이터 의존성, 분기 조건 미확정, 하드웨어 자원 충돌로 인해 다음 사이클 실행이 지연되는 현상
- 배경/필요성: 선행 연산 미완료 값의 오참조 및 분기 예측 오류를 방지하고 **파이프라인 연속 실행 및 연산 일관성 보장**

#### 한줄 요약

- 데이터(RAW), 제어(Branch), 구조적(Resource) 충돌을 **포워딩·예측·자원분리**로 극복

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CPI(Cycles Per Instruction)**: 명령어 1개를 완료하는 데 소요되는 평균 클록 주기 수(해저드 발생 시 증가).
- **버블(Bubble)**: 스톨 발생 시 파이프라인에 주입되는 NOP(No Operation) 무효 사이클.

</details>

- 원인별 **데이터(포워딩), 제어(분기 예측), 구조적(자원 복제)** 완화 기법 차별 적용
- 해저드로 인한 **버블(Bubble)** 및 **플러시(Flush)** 누적에 따른 프로세서 처리량 저하 방어
- 이상적 $IPC=1$ 달성을 저해하는 **CPI 오버헤드(Stall Cycles)** 최소화 통제

#### 한줄 요약

- 해저드 감지 및 완화 제어로 **버블·플러시 페널티 최소화**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지기(Hazard Detection Unit)**: 레지스터 번호와 메모리 읽기/쓰기 제어 신호를 비교하여 충돌을 실시간 감지하는 논리 회로.
- **포워딩 유닛(Forwarding Unit)**: EX/MEM 및 MEM/WB 레지스터의 결과를 ALU 입력 멀티플렉서로 우회 공급하는 유닛.

</details>

```text
[ 해저드 탐지 및 제어 유닛 아키텍처 ]
+-------------------------------------------------------------------------+
|  [ 파이프라인 레지스터 ] ──(비교)──> [ 해저드 감지기 ]                    |
|         │                                             │                 |
|         ├─ 데이터 의존성 ──> [ 포워딩 유닛 ]                             |
|         ├─ 제어 조건     ──> [ 분기 제어기 및 플러시 신호 ]               |
|         └─ 구조적 충돌   ──> [ 자원 중재기 및 스톨 신호 ]                 |
+-------------------------------------------------------------------------+
```

선의 의미: 파이프라인 레지스터 분석을 통해 데이터, 제어, 구조적 해저드를 감지하고 제어하는 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 해저드 감지기 | 레지스터 번호 비교를 통해 충돌 및 의존성 탐지 |
| 포워딩 경로 | 선행 결과를 연산기 입력으로 우회 |
| 분기 제어기 | 예측 검증 후 **파이프라인 플러시** 및 복구 제어 |
| 자원 중재기 | 자원 충돌 시 우선순위를 할당하고 지연 신호 제어 |

#### 한줄 요약

- **해저드 감지기** 중심의 포워딩 유닛, 분기 제어기, 자원 중재기 협업

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RAW(Read After Write)**: 선행 명령어가 데이터를 쓰기 전에 후속 명령어가 읽으려고 할 때 발생하는 진성 데이터 의존성.

</details>

```text
[ 파이프라인 레지스터 정보 분석 ]
              │
              ▼
       [ 1. 해저드 탐지 ]
              │
     ┌────────┼────────┐
     ▼        ▼        ▼
 [ 데이터 ] [ 제어 ] [ 구조적 ]
     │        │        │
     ▼        ▼        ▼
 [ 포워딩 ] [ 플러시 ] [ 스톨 ]
     │        │        │
     ▼        ▼        ▼
     [ 2. 완화 방식 결정 ]
              │
              ▼
       [ 3. 상태 갱신 ]
```

**동작 원리**

1. **해저드 탐지**: 소스 레지스터(Rs1, Rs2)와 이전 단계 목적 레지스터(Rd) 일치 여부 비교
2. **완화 방식 결정**:
   - 데이터 해저드: ALU 결과 바이패스 포워딩 수행 (Load-Use 시 1클록 스톨 병행)
   - 제어 해저드: 분기 예측 성공 시 무감속 진행, 실패 시 잘못 인출된 명령어 플러시 및 타깃 주소 재인출
   - 구조적 해저드: 메모리/레지스터 포트 충돌 시 후속 명령어에 1클록 스톨 버블 주입
3. **상태 갱신**: 파이프라인 레지스터 및 PC 갱신 후 정상 실행 연속 가동

#### 한줄 요약

- 충돌 탐지 후 **포워딩 바이패스, 분기 플러시, 스톨 버블** 주입으로 안전 제어

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Load-Use 해저드**: 메모리에서 데이터를 읽어오는 Load 명령어 직후 해당 레지스터를 사용할 때 발생하는 1클록 불가피 지연.

</details>

| 해저드 분류 | 데이터 해저드 (Data) | 제어 해저드 (Control) | 구조적 해저드 (Structural) |
|:---|:---|:---|:---|
| 발생 원인 | 선후 명령어 간 데이터 의존성 (RAW, WAR, WAW) | 조건 분기문(Branch) 타깃 미확정 및 분기 예측 실패 | 동일 사이클 내 단일 하드웨어 자원 동시 점유 시도 |
| 핵심 특징 | 연산 결과 미기록 상태에서 읽기 시도 (RAW 최다) | 깊은 파이프라인일수록 파이프라인 플러시 페널티 증대 | 하버드 구조 미도입(단일 메모리) 시 명령어/데이터 충돌 |
| 완화 대책 | 데이터 포워딩(Bypassing), 명령어 스케줄링 | 동적 분기 예측기(2-bit BHT), BTB, 조기 분기 판정 | L1 I/D 분리 캐시 도입, 다중 포트 레지스터 파일 |

#### 한줄 요약

- 데이터는 **포워딩**, 제어는 **분기 예측**, 구조는 **자원 복제(I/D 캐시)**로 대응

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **BTB(Branch Target Buffer)**: 분기 명령어 주소와 타깃 주소를 캐싱하여 인출 단계에서 즉시 다음 PC를 제공하는 하드웨어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 산술 연산 시 데이터 의존성으로 인한 대기 지연 | 연산 결과를 다음 입력으로 즉각 우회하는 **포워딩** 적용 | 쓰기 지연 완벽 은닉 및 사이클 성능 유지 |
| **적재-사용 의존**으로 포워딩 해소 불가 | 하드웨어 지연 주입 및 컴파일러 **명령 스케줄링** 연동 | 지연 슬롯을 무해한 연산으로 채워 체감 지연 축소 |
| 타깃 주소 지연 및 실패로 깊은 파이프라인 파기 손실 | **분기 예측기**, **분기 대상 버퍼** 적용 | 예측 적중률 향상과 파기 페널티 대폭 감소 |
| 통합 메모리 사용 시 명령어 및 데이터의 동시 접근 자원 충돌 | 칩 캐시 분리 및 **다중 포트** 적용 | 구조적 해저드 발생 가능성 원천 차단 |

#### 한줄 요약

- **포워딩·로드 지연 슬롯 스케줄링·BTB 예측·다중 포트**로 성능 저하 방어

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **비순차 실행(Out-of-Order Execution, OoO)**: 데이터 의존성이 없는 후속 명령어를 먼저 실행하여 해저드 스톨을 원천 은닉하는 고급 아키텍처.

</details>

- 하드웨어 면적·전력 비용과 성능 목표를 종합 고려한 **최적 해저드 감지 및 완화 아키텍처 설계**

#### 한줄 요약

- **비용·전력 대비 성능 이득**에 맞춘 최적 해저드 제어 회로 적용
