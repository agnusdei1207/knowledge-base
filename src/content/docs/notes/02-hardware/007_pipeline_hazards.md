## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 중첩 실행 명령어가 데이터·제어 흐름·하드웨어 자원을 두고 충돌해 올바른 진행이 깨지는 상황.
- **스톨(Stall)**: 충돌이 해소될 때까지 파이프라인 단계 진행을 멈추고 버블을 삽입하는 제어.
- **플러시(Flush)**: 잘못 진행한 명령어를 NOP으로 교체해 파이프라인에서 제거하는 복구 제어.

</details>

- 정의/개념: 중첩 실행 명령어 간 **데이터 의존성**이나 **자원 경합**으로 정상 실행이 지연되는 파이프라인 장애 현상
- 배경/필요성: 미해결 충돌 발생 시 잘못된 피연산자 참조 및 **파이프라인 스톨(Stall)** 로 성능 저하 초래

#### 한줄 요약
- 여러 명령어를 겹쳐 처리하면 앞 명령어의 결과·분기 방향·하드웨어를 기다려야 하는 충돌이 생겨, 이를 정확하고 신속하게 해소해야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어의 ALU 결과를 레지스터 기록 전에 후속 EX 단계로 직접 전달하는 우회 경로.
- **분기 예측(Branch Prediction)**: 실제 분기 결과가 확정되기 전에 다음 인출 주소를 추정해 파이프라인을 계속 채우는 기법.
- **버블(Bubble)**: 스톨로 인해 유효 명령어가 없는 파이프라인 슬롯; NOP으로 채워 데이터 경로를 통과.

</details>

- 데이터 해저드: **포워딩** 또는 스톨로 의존성 보존해 잘못된 피연산자 사용 방지
- 제어 해저드: **분기 예측**과 오예측 플러시로 인출 연속성 유지와 잘못된 경로 폐기
- 구조 해저드: 자원 분리·다중 포트·중재로 동시 자원 요청에 따른 **스톨** 방지

#### 한줄 요약
- 해저드는 원인이 다르지만, 결국 잘못된 값을 쓰지 않고 다음 명령어를 얼마나 덜 기다리게 하느냐의 선택 문제다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지기(Hazard Detection Unit)**: 파이프라인 레지스터의 소스·목적 레지스터와 자원 요청을 비교해 충돌을 판정하는 회로.
- **분기 제어기(Branch Control Unit)**: 분기 결과와 예측 결과를 비교해 PC 복구와 플러시를 제어하는 회로.
- **자원 중재기(Resource Arbiter)**: 동시에 요청된 공유 자원의 사용 순서와 대기를 결정하는 회로.

</details>

```text
[파이프라인 해저드 제어]
├─ 해저드 감지기  (레지스터 의존성·자원 충돌 판정)
├─ 포워딩 경로   (EX/MEM·MEM/WB → EX 단계 우회)
├─ 분기 제어기   (예측 비교·PC 복구·플러시)
└─ 자원 중재기   (공유 메모리·실행 유닛 접근 순서)
```

선의 의미: 가지(`├─`)는 해저드 제어 서브시스템의 소유 관계; 각 구성요소는 파이프라인 단계와 병렬로 동작

| 구성요소 | 책임 |
|:---|:---|
| 해저드 감지기 | 데이터 의존성과 자원 충돌 판정·**스톨** 신호 발생 |
| 포워딩 경로 | 준비된 ALU·메모리 결과를 EX 단계로 직접 우회 |
| 분기 제어기 | 오예측 확인 후 PC 복구와 **플러시** 제어 |
| 자원 중재기 | 공유 자원 동시 요청 조정으로 구조 해저드 해소 |

#### 한줄 요약
- 해저드 제어 회로는 충돌을 먼저 탐지하고, 데이터는 우회 전달·제어는 경로 복구·자원은 순서 정렬로 각각 다르게 해소한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 레지스터에 쓰기 전에 후속 명령어가 그 값을 읽으려는 진성 의존성.
- **적재-사용 의존(Load-Use Dependency)**: 로드 결과가 MEM 완료 후 확정돼 즉시 EX 포워딩이 불가한 특수 RAW 의존성.
- **적재 지연 은닉(Load-Use Latency Hiding)**: 독립 명령어 실행을 적재 대기 시간과 겹쳐 유효 스톨 사이클을 줄이는 기법·효과.

</details>

```text
명령어 실행 중 해저드 감지기 동작
         │
         ▼
충돌 유형 판정
         │
    ┌────┴────────────────┐
    │                     │
RAW·적재-사용 의존    분기 결과 미확정
    │                     │
    ▼                     ▼
포워딩 가능?        분기 예측 비교
    │                     │
 예 → 포워딩 경로   예측 일치? → 계속 실행
 아니오 → 스톨·버블 예측 오류 → 플러시·PC 복구
삽입 후 포워딩
```

**동작 원리**

1. **RAW 및 적재-사용 의존 판정**: 포워딩으로 즉시 우회하고 적재-사용은 스톨 처리
2. **분기 예측 비교 및 제어**: 오예측 시 플러시 후 정확한 분기 목표 복구

#### 한줄 요약
- 해저드 감지기는 충돌 유형을 보고 포워딩·스톨·플러시 중 비용이 가장 적은 해소 방법을 선택한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다중 포트(Multi-port)**: 하나의 자원에 여러 독립 접근 경로를 제공해 동시 접근을 허용하는 구조.
- **인터록(Interlock)**: 해저드가 해소될 때까지 명령어 진행을 자동 중단하는 하드웨어 제어 회로.

</details>

| 해저드 유형 | 데이터 해저드 | 제어 해저드 | 구조 해저드 |
|:---|:---|:---|:---|
| 적용 기준 | **RAW** 의존성으로 값 준비 지연 | 분기·점프로 다음 PC 미확정 | 같은 자원의 동시 사용 요구 |
| 핵심 특징 | **포워딩** 또는 인터록으로 의존성 보존 | **분기 예측**·플러시·PC 복구 | 자원 분리·다중 포트·중재 |
| 한계 | 적재-사용 의존은 스톨 불가피 | 오예측 시 진행 명령어 플러시 비용 | 면적·전력·설계 복잡도 증가 |

#### 한줄 요약
- 값이 아직 없으면 데이터 해저드, 다음 주소를 모르면 제어 해저드, 같은 장치를 동시에 원하면 구조 해저드다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 이전 분기의 주소·목표 주소·방향을 캐싱해 다음 PC 예측 속도를 높이는 구조.
- **명령어 스케줄링(Instruction Scheduling)**: 컴파일러가 데이터 의존성을 고려해 명령어 순서를 재배치해 스톨을 줄이는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **RAW** 의존성으로 결과 준비 전 사용 | **포워딩** 경로와 인터록 적용 | 오래된 값 사용 방지·스톨 최소화 |
| **적재-사용 의존**으로 로드 결과 즉시 사용 불가 | 스톨 1사이클 삽입·**명령어 스케줄링**으로 **적재 지연 은닉** | 유효 스톨 사이클 감소 |
| 분기 목표와 방향 불확실로 인출 중단 | **BTB**·분기 예측·오예측 시 플러시 | 인출 연속성·예측 성공률 향상 |
| 단일 메모리·실행 유닛에 동시 요청 집중 | 자원 분리·다중 포트 설계 | 구조 해저드 빈도 감소 |

#### 한줄 요약
- 데이터는 준비 시점에 맞추고, 분기는 다음 주소를 미리 찾고, 자원은 동시에 쓸 수 있게 늘려 해저드 비용을 줄인다.

## Ⅶ. 결론

- 데이터는 **포워딩**, 제어는 **분기 예측**, 자원은 **하드웨어 분리** 선택

#### 한줄 요약
- 해저드 대책은 많이 넣을수록 좋은 것이 아니라, 정확성을 지키는 인터록 위에 필요한 처리량만큼의 포워딩과 예측을 더하는 선택이다.
