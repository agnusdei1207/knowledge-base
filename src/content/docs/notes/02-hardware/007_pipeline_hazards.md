## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 명령어 의존성, 조건 분기, 자원 충돌로 인해 명령어를 계속 실행하지 못하는 구조적 충돌 조건이다.
- **스톨(Stall)**: 해저드 충돌이 해결될 때까지 하위 단계를 멈추고 빈 명령어를 투입하는 제어 기법이다.
- **포워딩(Forwarding)**: 연산 결과를 레지스터 최종 기록 전에 다음 연산기 입력으로 우회 전송하여 대기를 방지하는 기술이다.
- **플러시(Flush)**: 분기 예측 오류 시 이미 인출 단계에 잘못 적재된 기계어 명령어를 무효화하여 제거하는 작업이다.

</details>

- 정의: 명령어 처리 과정에서 의존성, 조건 미확정, 자원 경합으로 인해 연속 실행 흐름이 정지되는 **파이프라인 해저드** 현상
- 배경: 선행 명령어 처리 전의 잘못된 값을 후속 명령어가 사용하거나 잘못된 분기를 수행하여 발생하는 실행 오류를 방지하기 위함

#### 한줄 요약

- 하드웨어 감지 회로를 구동하여 데이터, 제어, 구조 해저드를 감지하고 우회, 정지, 파기 제어를 통해 연산 일관성을 유지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **명령어당 사이클 수(Cycles Per Instruction, CPI)**: 단일 기계어 명령어를 완결하는 데 소비되는 평균 클록 주기 수이다.
- **버블(Bubble)**: 정지나 파기 제어로 인해 유효한 명령어가 실행되지 못하고 비어 있는 파이프라인 슬롯이다.
- **명령 처리량(Instruction Throughput)**: 단위 시간당 완료되어 아키텍처 상태에 반영되는 명령어의 총 개수이다.

</details>

- 발생 원인에 따라 **포워딩**, 분기 예측, 자원 복제 등 완화 기법을 차별적으로 적용함.
- 해저드로 인해 발생하는 **버블** 및 **플러시** 주기가 누적될수록 실제 프로세서의 **명령 처리량**이 지연됨.
- 해저드 발생 빈도와 지연 주기에 비례하여 실제 **명령어당 사이클 수** 오버헤드가 이상적 환경보다 누적 증가함.

#### 한줄 요약

- 완화 제어를 통해 지연 주기를 은닉하고 실제 클록당 사이클 오버헤드를 최소화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지기(Hazard Detection Unit)**: 레지스터 번호를 실시간 비교하여 충돌을 감지하는 제어 논리회로이다.
- **포워딩 경로(Forwarding Path)**: 이전 파이프라인 레지스터의 연산 출력을 다음 입력으로 즉각 회환시키는 우회 통로이다.
- **자원 중재기(Resource Arbiter)**: 자원을 동시 요구하는 제어 신호 간 우선순위를 할당하는 중재 회로이다.
- **분기 제어기(Branch Control Unit)**: 조건과 예측 주소를 비교하여 실제 분기 및 파기 신호를 발생하는 장치이다.
- **파이프라인 레지스터(Pipeline Register)**: 각 단계 사이에 데이터를 격리 전달하는 래치 장치이다.
- **파이프라인 플러시(Pipeline Flush)**: 잘못 인출된 파이프라인 내부 명령어를 폐기하고 주소를 올바르게 복구하는 연산이다.

</details>

```text
[ 해저드 탐지 및 제어 유닛 ]
+-------------------------------------------------------------------------+
|  [ 파이프라인 레지스터 ] ──(비교)──> [ 해저드 감지기 ]                    |
|         │                                             │                 |
|         ├─ 데이터 의존성 ──> [ 포워딩 유닛 ]                             |
|         ├─ 제어 조건     ──> [ 분기 제어기 및 플러시 신호 ]               |
|         └─ 구조적 충돌   ──> [ 자원 중재기 및 스톨 신호 ]                 |
+-------------------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| 해저드 감지기 | 레지스터 번호 비교를 통해 충돌 및 의존성 탐지 |
| 포워딩 경로 | 선행 결과를 연산기 입력으로 우회 |
| 분기 제어기 | 예측 검증 후 **파이프라인 플러시** 및 복구 제어 |
| 자원 중재기 | 자원 충돌 시 우선순위를 할당하고 지연 신호 제어 |

#### 한줄 요약

- 해저드 감지기가 충돌을 탐지하면 포워딩, 분기 제어기, 중재기가 적절한 완화 조치를 실행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **원천 레지스터(Source Register)**: 현재 명령어 연산에 사용하기 위해 레지스터 파일에서 읽어오는 레지스터이다.
- **목적 레지스터(Destination Register)**: 이전 명령어가 연산 결과를 최종 기록하기 위해 지정한 레지스터이다.
- **완화 제어 신호(Mitigation Control Signal)**: 감지된 해저드 종류에 따라 포워딩 선택, 지연, 파기를 구동하는 제어 비트이다.

</details>

```text
[ 파이프라인 레지스터 정보 분석 ]
              │
              ▼
       [ 1. 해저드 탐지 ]
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
[ 데이터 ] [ 제어 ]  [ 구조적 ]
    │         │         │
    ▼         ▼         ▼
[ 포워딩 ] [ 플러시 ] [ 스톨 ]
    │         │         │
    ▼         ▼         ▼
    [ 2. 완화 방식 결정 ]
              │
              ▼
       [ 3. 상태 갱신 ]
```

### 동작 원리

1. 해저드 탐지: **해저드 감지기**가 원천 레지스터 및 메모리 접근 신호를 비교함.
2. 완화 방식 결정:
   - 데이터: 우회 연동이 가능하면 **완화 제어 신호**를 켜고, 적재 의존 시 지연을 주입함.
   - 제어: 분기 예측 성공 시 진행하고 실패 시 파기 및 올바른 주소를 전송함.
   - 구조적: 자원 충돌 시 후속 명령에 지연을 주입함.
3. 상태 갱신: 레지스터 갱신 및 빈 명령 주입 후 파이프라인 가동을 계속함.

#### 한줄 요약

- 레지스터 및 자원 충돌을 탐지한 뒤 데이터, 제어, 구조에 맞는 제어 신호를 생성하여 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 이전 명령어의 결과 기록이 완료되지 않은 상태에서 다음 명령어가 레지스터를 읽을 때 발생한다.
- **제어 해저드(Control Hazard)**: 조건 분기 명령어의 주소 결정 전 후속 명령어를 인출하여 발생하는 불확정 문제이다.
- **구조적 해저드(Structural Hazard)**: 동일 클록 주기에 여러 단계가 단일 물리 자원을 동시 점유할 때 발생한다.
- **쓰기 후 읽기(Read After Write)**: 이전 명령의 쓰기 전에 다음 명령이 먼저 읽어 발생하는 진성 의존성 문제이다.
- **추측 인출(Speculative Fetch)**: 분기 조건 결과 확정 전에 분기 예측기를 기반으로 다음 명령어를 미리 인출하는 동작이다.
- **자원 복제(Resource Duplication)**: 자원 경합을 해소하기 위해 캐시를 분리하고 포트를 다중화하는 하드웨어 증설 설계이다.

</details>

| 비교 항목 | 데이터 해저드 | 제어 해저드 | 구조적 해저드 |
|:---|:---|:---|:---|
| 발생 원인 | 선후 명령어 간 **쓰기 후 읽기** 의존성 | 결과 결정 전 **추측 인출**의 예측 실패 | 단일 하드웨어 자원의 동시 점유 시도 |
| 치명도 | 빈번함 (연속 연산에서 다수 발생) | 실패 시 깊은 파이프라인일수록 큰 페널티 발생 | 메모리가 잘 분리된 칩에서는 거의 발생 안 함 |
| 완화 대책 | **포워딩**, 명령 스케줄링 | 분기 예측기 구동 및 조기 판정 회로 적용 | 듀얼 캐시 분리 등 **자원 복제** |

#### 한줄 요약

- 해저드는 쓰기 후 읽기 의존, 분기 미스, 자원 점유로 구분되며 각각 포워딩, 예측기, 자원 복제로 대응한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 적재 명령 직후 해당 레지스터를 연산 피연산자로 사용할 때 포워딩만으로 완벽 해소가 불가능하여 지연이 필요한 현상이다.
- **분기 대상 버퍼(Branch Target Buffer)**: 분기 주소와 타깃 주소를 캐싱하여 인출 단계에서 다음 카운터를 제공하는 하드웨어이다.
- **명령 스케줄링(Instruction Scheduling)**: 컴파일러가 의존 관계인 명령어 사이에 의존성 없는 다른 명령어를 배치하는 최적화 기법이다.
- **분기 예측기(Branch Predictor)**: 카운터를 활용하여 조건 분기의 진행 방향을 동적으로 추정하는 장치이다.
- **다중 포트(Multi-Port Register File)**: 다수의 읽기 쓰기 포트를 제공하여 자원 구조적 해저드를 배제하는 레지스터 파일 구성이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 산술 연산 시 데이터 의존성으로 인한 대기 지연 | 연산 결과를 다음 입력으로 즉각 우회하는 **포워딩** 적용 | 쓰기 지연 완벽 은닉 및 사이클 성능 유지 |
| **적재-사용 의존**으로 포워딩 해소 불가 | 하드웨어 지연 주입 및 컴파일러 **명령 스케줄링** 연동 | 지연 슬롯을 무해한 연산으로 채워 체감 지연 축소 |
| 타깃 주소 지연 및 실패로 깊은 파이프라인 파기 손실 | **분기 예측기**, **분기 대상 버퍼** 적용 | 예측 적중률 향상과 파기 페널티 대폭 감소 |
| 통합 메모리 사용 시 명령어 및 데이터의 동시 접근 자원 충돌 | 칩 캐시 분리 및 **다중 포트** 적용 | 구조적 해저드 발생 가능성 원천 차단 |

#### 한줄 요약

- 포워딩 경로, 명령 스케줄링, 분기 대상 버퍼 기반 예측기, 캐시 자원 복제를 통합하여 해결한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **면적•전력 비용(Area & Power Cost)**: 하드웨어 회로 추가 및 포트 증설 시 유발되는 칩 면적 증가와 전력 소비 오버헤드이다.
- **추가 CPI(CPI Overhead)**: 해저드를 완화하지 못하고 정지나 파기가 발생하여 추가로 소모되는 평균 명령어당 클록 주기의 페널티이다.
- **완화 회로 선택 기준(Hazard Mitigation Criteria)**: 칩의 성능 목표와 물리적 하드웨어 비용 오버헤드 간의 관계를 종합 평가하는 기준이다.

</details>

- **완화 회로 선택 기준**에 맞춰 의존성이 높으면 포워딩, 분기 손실이 크면 예측기를 적용

#### 한줄 요약

- 성능 목표와 하드웨어 면적 및 전력 소비 비용 간의 상충 관계를 고려하여 최적의 해저드 완화 회로를 설계해야 한다.
