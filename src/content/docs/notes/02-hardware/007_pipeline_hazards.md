## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라인 해저드(Pipeline Hazard)**: 중첩 실행 명령어가 데이터, 제어 흐름, 하드웨어 자원을 두고 충돌하는 상황입니다.
- **스톨(Stall)**: 충돌이 해소될 때까지 일부 파이프라인 단계를 멈추는 제어입니다.
- **플러시(Flush)**: 잘못 진행한 명령어를 무효화해 파이프라인에서 제거하는 제어입니다.

</details>

- 정의/개념: 명령어 중첩으로 정확한 진행이 깨지는 **파이프라인 충돌**
- 배경/필요성: 잘못된 결과를 막고 처리량 손실을 최소화하는 제어 필요

#### 한줄 요약

- 여러 명령어를 겹쳐 처리하면 앞 명령어의 결과나 분기 방향, 하드웨어 자원을 서로 기다리는 일이 생기므로 이를 조정해야 합니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어 결과를 레지스터 기록 전에 후속 실행 단계로 직접 보내는 우회 경로입니다.
- **분기 예측(Branch Prediction)**: 실제 분기 결과가 나오기 전에 다음 인출 주소를 추정하는 기법입니다.
- **버블(Bubble)**: 스톨 때문에 유효한 명령어가 없는 파이프라인 슬롯입니다.

</details>

- 데이터 해저드: 포워딩 또는 스톨로 **의존성 보존**
- 제어 해저드: 분기 예측과 플러시로 **인출 경로 복구**
- 구조 해저드: 자원 분리와 중재로 **동시 요청 조정**

#### 한줄 요약

- 해저드는 원인에 따라 다르지만, 결국 잘못된 값을 쓰지 않고 다음 명령어를 얼마나 덜 기다리게 하느냐의 문제입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해저드 감지기(Hazard Detection Unit)**: 파이프라인의 레지스터와 자원 정보를 비교해 충돌을 판정하는 회로입니다.
- **분기 제어기(Branch Control Unit)**: 분기 결과와 예측 결과를 비교해 PC 복구와 플러시를 제어하는 회로입니다.
- **자원 중재기(Resource Arbiter)**: 동시에 요청된 공유 자원의 사용 순서와 대기를 결정하는 회로입니다.

</details>

```text
[해저드 제어]
├─ 해저드 감지기
├─ 포워딩 경로
├─ 분기 제어기
└─ 자원 중재기
```

| 구성요소 | 책임 |
|:---|:---|
| 해저드 감지기 | 데이터 의존성과 자원 충돌 판정 |
| 포워딩 경로 | 준비된 선행 결과의 우회 전달 |
| 분기 제어기 | 예측 오류의 PC 복구와 플러시 |
| 자원 중재기 | 공유 자원의 접근 순서 결정 |

#### 한줄 요약

- 해저드 제어 회로는 먼저 충돌을 찾아내고, 데이터는 우회하고, 분기는 되돌리고, 자원은 차례를 정합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 값을 쓰기 전에 후속 명령어가 그 값을 읽으려는 진성 의존성입니다.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어 주소를 보관하는 레지스터입니다.

</details>

```text
[1. 충돌 정보 비교]
          │
          ▼
[2. 해저드 유형 판정]
          │
          ▼
[3. 우회·대기·복구 선택]
          │
          ▼
[4. PC·단계 상태 갱신]
```

동작 원리:

1. 충돌 정보 비교: 레지스터 의존성과 자원 요청 확인
2. 해저드 유형 판정: RAW, 분기 결과, 공유 자원 충돌 분류
3. 우회·대기·복구 선택: 포워딩·스톨·플러시 중 필요한 제어 선택
4. PC·단계 상태 갱신: 선택한 제어 신호를 현재 파이프라인에 반영

#### 한줄 요약

- 해저드 제어는 충돌을 본 뒤 무조건 멈추지 않고, 바로 전달할 수 있는지와 되돌려야 하는지를 먼저 판단합니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다중 포트(Multi-port)**: 하나의 저장소나 자원에 여러 독립 접근 경로를 제공하는 구조입니다.
- **인터록(Interlock)**: 해저드가 해소될 때까지 명령어 진행을 자동으로 멈추는 제어 회로입니다.

</details>

| 해저드 유형 | 데이터 | 제어 | 구조 |
|:---|:---|:---|:---|
| 적용 기준 | RAW 의존성으로 값 준비 지연 | 분기·점프로 다음 PC 미확정 | 같은 자원의 동시 사용 요구 |
| 핵심 특징 | 포워딩 또는 인터록 제어 | 예측, 플러시, PC 복구 | 자원 분리, 다중 포트, 중재 |
| 한계 | 적재 결과는 즉시 우회 불가 가능성 | 오예측 시 진행 명령어 폐기 | 면적·전력·복잡도 증가 |

#### 한줄 요약

- 값이 아직 없으면 데이터 해저드, 다음 주소를 모르면 제어 해저드, 같은 장치를 동시에 원하면 구조 해저드입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 로드한 값이 준비되기 전에 바로 다음 명령어가 그 값을 요구하는 RAW 의존성입니다.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 이전 분기의 주소와 목표 주소를 저장해 다음 PC 예측을 돕는 구조입니다.
- **명령어 스케줄링(Instruction Scheduling)**: 의존성이 없는 명령어 순서를 조정해 대기 시간을 줄이는 기법입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 연산 결과 RAW 의존성으로 다음 단계 정지 | 포워딩과 인터록 적용 | 오래된 값 사용과 불필요한 대기 방지 |
| 적재-사용 의존으로 결과 준비 전 사용 | 스톨 삽입과 명령어 스케줄링 | 데이터 준비 시점에 맞는 실행 |
| 분기 목표 주소와 방향이 불확실 | BTB와 분기 예측 적용 | 인출 연속성과 예측 성공률 향상 |
| 단일 메모리·실행 유닛에 요청 집중 | 자원 분리와 다중 포트 설계 | 구조 해저드 빈도 감소 |

#### 한줄 요약

- 데이터는 준비 시점에 맞추고, 분기는 다음 주소를 미리 찾고, 자원은 동시에 쓸 수 있게 늘려 해저드 비용을 줄입니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **명령 처리량(Instruction Throughput)**: 일정 시간에 완료되는 명령어 수로 측정하는 실행 성능입니다.

</details>

- 정확성 보장이 우선이면 인터록·플러시를 먼저 적용하고, 목표 **명령 처리량**이 높으면 포워딩·예측·자원 분리를 추가하되 면적·전력 비용으로 제어 수준 결정

#### 한줄 요약

- 해저드 대책은 많이 넣을수록 좋은 것이 아니라, 정확성을 지키는 기본 제어 위에 필요한 처리량만큼의 우회와 예측을 더하는 선택입니다.
