## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm 아키텍처(Arm Architecture)**: 저전력 로드·스토어 기반 연산 구조에 다단계 권한 격리와 모듈형 확장을 결합한 산업 표준 규격.
- **예외 수준(Exception Level, EL)**: 보안성과 격리를 위해 프로세서 권한을 EL0(앱)부터 EL3(보안 모니터)까지 4단계로 계층화한 보안 아키텍처.
- **실행 상태(Execution State)**: 프로세서 코어가 실행할 레지스터 폭 및 명령어 포맷(AArch64 / AArch32)을 규정하는 동작 모드.

</details>

- 정의/개념: 저전력 로드·스토어 기반 RISC 연산 구조와 4단계 예외 수준(EL0~EL3) 하드웨어 권한 격리를 규정한 글로벌 표준 Arm 아키텍처
- 배경/필요성: 모바일 및 엣지 기기의 엄격한 전력 제약을 극복하고 **하드웨어 가상화 및 TrustZone 기반 보안 격리 체계 확립**

#### 한줄 요약

- **저전력 로드·스토어 구조와 4단계 예외 수준(EL0~EL3)** 기반의 프로세서 아키텍처

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NEON / SVE**: 128비트 고정 벡터(NEON) 및 가변 벡터 폭(Scalable Vector Extension, SVE)을 지원하는 병렬 연산 엔진.
- **TrustZone**: 보안 세계(Secure World)와 일반 세계(Non-secure World)를 하드웨어적으로 완전 분리하는 Arm 보안 기술.

</details>

- **로드•스토어 구조** 채택을 통한 연산 시 메모리 접근 지연 우회 및 실행 효율 극대화
- **실행 상태(AArch64/32)** 전환과 **예외 수준(EL0~EL3)** 결합을 통한 레거시 호환 및 하드웨어 권한 격리
- 명령어 규격 라이선스와 사전 완성된 **코어 IP 라이선싱** 형태의 이원화 공급 체계

#### 한줄 요약

- **AArch64/AArch32 실행 상태**와 **계층적 예외 수준(EL)**의 유연한 결합

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **EL0 ~ EL3**: EL0(User App), EL1(OS Kernel), EL2(Hypervisor), EL3(Secure Monitor).

</details>

```text
[ Arm 프로세서 아키텍처 계층 구조 ]
┌───────────────────────────────────────────────────────────┐
│ 실행 상태 : AArch64 (64-bit)  /  AArch32 (32-bit)         │
├───────────────────────────────────────────────────────────┤
│ 예외 수준 (하드웨어 권한 격리)                            │
│  - EL0 : 애플리케이션 (User)                              │
│  - EL1 : 운영체제 커널 (Kernel)                           │
│  - EL2 : 하이퍼바이저 및 가상화 (Hypervisor)              │
│  - EL3 : 보안 모니터 (Secure Monitor / TrustZone)         │
├───────────────────────────────────────────────────────────┤
│ 벡터 및 부동소수점 엔진 : NEON (128bit) / SVE (가변 폭)   │
└───────────────────────────────────────────────────────────┘
```

선의 의미: 실행 상태, 4단계 예외 수준(EL0~EL3), NEON/SVE 벡터 엔진으로 구성된 Arm 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| AArch64 | 64비트 레지스터 및 전용 명령어 실행 |
| AArch32 | 32비트 레거시 **레지스터 집합** 호환 실행 |
| 예외 수준 | 4단계 **예외 수준 격리**를 통한 권한 분리 |
| 벡터 엔진 | 고정 및 가변 폭의 벡터 병렬 연산 수행 |

#### 한줄 요약

- **AArch64/32 실행 상태, EL0~EL3 권한 계층, NEON/SVE 벡터 엔진** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PSTATE**: 프로세서 조건 플래그, 인터럽트 마스크, 현재 EL을 담은 상태 필드.
- **SPSR / ELR**: 복귀 시 상태를 복원하기 위한 SPSR(Saved PSR) 및 복귀 주소를 보관하는 ELR(Exception Link Register).
- **VBAR**: 예외 벡터 테이블의 베이스 주소를 지시하는 Vector Base Address Register.

</details>

```text
[ 소프트웨어 실행 중 (EL0) ]
         │
         ▼ 시스템 콜(SVC) 또는 하드웨어 인터럽트 발생
[ 하드웨어 트랩 및 상태 자동 백업 ]
 1. 현재 PSTATE ──> SPSR_ELx (Saved Program Status Register)에 백업
 2. 복귀 주소 PC ──> ELR_ELx (Exception Link Register)에 저장
 3. VBAR_ELx 참조 ──> 해당 예외 핸들러 오프셋으로 분기
         │
         ▼
[ 예외 처리기 (Handler) 실행 (EL1/EL2) ]
         │
         ▼ ERET (Exception Return) 명령어 실행
[ 프로세서 상태 복원 및 원본 복귀 ]
 SPSR 및 ELR 복원 ──> 이전 실행 지점 재개
```

**동작 원리**

1. **상태 저장**: 예외 발생 시 하드웨어가 현재 PSTATE와 복귀 주소를 SPSR_ELx 및 ELR_ELx에 자동 백업
2. **벡터 분기**: VBAR_ELx에 설정된 베이스 주소에 예외 유형별 오프셋을 더해 벡터 테이블로 점프
3. **핸들러 실행**: 커널(EL1) 또는 하이퍼바이저(EL2)가 서비스 루틴 및 인터럽트 처리 수행
4. **상태 복원**: ERET 명령어 실행으로 SPSR과 ELR을 프로세서 레지스터로 복구하고 원본 앱으로 복귀

#### 한줄 요약

- 예외 발생 시 **SPSR/ELR 자동 저장, VBAR 분기, ERET 복귀** 사이클 완결

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SoC(System on Chip)**: CPU 코어, GPU, NPU, 메모리 컨트롤러를 단일 실리콘 다이에 집적한 고집적 반도체.

</details>

| 비교 항목 | Arm 아키텍처 (AArch64) | x86-64 아키텍처 (x86_64) |
|:---|:---|:---|
| 적용 기준 | 모바일, 임베디드, 고효율 클라우드 서버 | 고성능 PC, 고부하 엔터프라이즈 서버 |
| 핵심 특징 | 로드·스토어 구조, 4단계 예외 수준(EL), NEON/SVE | 복합 명령어(CISC), Ring 0~3 보호 모드, AVX-512 |
| 한계 및 위험 | x86 레거시 바이너리 실행 시 에뮬레이션 오버헤드 | 복잡한 가변 길이 디코더로 인한 전력 및 발열 부담 |

#### 한줄 요약

- Arm은 **전력 효율 및 모바일/서버 확장**, x86-64는 **단일 스레드 성능 및 레거시 호환**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DVFS(Dynamic Voltage and Frequency Scaling)**: 부하량에 따라 클록 주파수와 공급 전압을 동적으로 조절하여 전력 소비를 최소화하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **네이티브 라이브러리** 이전 시 호환성 충돌 | 타깃 빌드 체계 및 동적 이진 변환 체계 구축 | 이종 아키텍처 마이그레이션 오류 해결 |
| 불필요한 특권 권한 점유로 시스템 안정성 훼손 | **최소 권한** 원칙 준수 및 모드 간 인터페이스 통제 | 사이드 채널 공격 및 보안 침해 파급력 차단 |
| 신규 벡터 명령어 실행 시 구형 단말 충돌 | **런타임 기능 탐지** 적용 및 **대체 코드** 제공 | 단말 세대에 구애받지 않는 실행 안정성 |
| 고부하 작업 중 발열 및 스로틀링 발생 | **전력 벤치마크** 기반 동적 주파수 전압 제어 | 시스템 전력 한도 내 최고 성능 유지 |

#### 한줄 요약

- **바이너리 변환·최소 권한·런타임 기능 탐지·DVFS**로 성능 및 안정성 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Neoverse**: 클라우드 데이터센터 및 HPC 워크로드를 겨냥하여 고성능과 고효율을 극대화한 Arm의 서버 전용 코어 아키텍처.

</details>

- 전력 효율, SoC 집적도, 보안 격리가 중요한 시스템 환경에서 **Arm 아키텍처 채택**

#### 한줄 요약

- **전력 제약과 멀티테넌트 보안 요구**에 맞춘 Arm 프로세서 최적 적용
