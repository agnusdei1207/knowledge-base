## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm 아키텍처(Arm Architecture)**: 로드·스토어 명령어 모델과 권한·예외·보안 동작을 정의하는 프로세서 아키텍처 계열.
- **프로파일(Profile)**: 응용 분야별로 Arm 기능 집합과 시스템 모델을 구분한 아키텍처 분류(A·R·M-profile).
- **실행 상태(Execution State)**: 레지스터 폭과 명령어 실행 규칙을 정하는 프로세서 상태(AArch64·AArch32).

</details>

- 정의/개념: 고정 길이 명령어와 **로드/스토어 구조** 기반으로 저전력 고효율 연산을 수행하는 RISC 프로세서 규격
- 배경/필요성: 모바일, 실시간 제어, 엔터프라이즈 서버 등 다양한 도메인별 전력 및 성능 요구조건 충족 필요

#### 한줄 요약
- Arm은 같은 명령어 계열 안에서도 스마트폰·실시간 제어·초소형 장치의 요구를 프로파일로 나눠 각각 최적화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **예외 수준(Exception Level, EL)**: 앱·OS·하이퍼바이저·펌웨어를 EL0~EL3으로 분리해 권한을 계층화하는 Arm A-profile의 실행 단계.
- **TrustZone**: 동일 코어에서 보안 상태(Secure World)와 비보안 상태(Normal World)를 분리해 자원 접근을 통제하는 Arm 보안 아키텍처.
- **벡터 확장(Vector Extension)**: 하나의 명령어로 여러 데이터 요소를 병렬 처리해 SIMD·ML 워크로드 처리량을 높이는 확장.

</details>

- 로드·스토어로만 메모리에 접근해 파이프라인 설계 단순화
- EL0~EL3 **예외 수준**으로 소프트웨어 권한 계층 분리
- **TrustZone**·벡터 확장·가상화 등을 선택 조합해 분야별 기능·전력·면적 최적화

#### 한줄 요약
- Arm은 연산을 단순한 메모리 규칙으로 처리하고, 권한·보안·병렬 연산을 필요한 분야에만 선택적으로 더한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **A-profile(Application Profile)**: 범용 OS·가상화·고성능 처리를 위한 Arm 프로파일.
- **R-profile(Real-Time Profile)**: 예측 가능한 결정적 응답 시간이 필요한 실시간 제어용 Arm 프로파일.
- **M-profile(Microcontroller Profile)**: 저전력·소형 임베디드 장치 제어용 Arm 프로파일.
- **AArch64**: 64비트 일반 목적 레지스터 31개와 A64 명령어 집합을 제공하는 Arm 실행 상태.

</details>

```text
[Arm 아키텍처]
├─ 프로파일
│  ├─ A-profile  (범용 OS·가상화)
│  ├─ R-profile  (실시간 제어)
│  └─ M-profile  (저전력 임베디드)
├─ 실행 상태
│  └─ AArch64 / AArch32
├─ 권한 모델
│  └─ 예외 수준 (EL0~EL3)
└─ 선택 확장
   ├─ TrustZone
   └─ 벡터 확장
```

선의 의미: 가지(`├─`)는 소유 관계; 선택 확장(`└─`)은 프로파일에 따라 지원 여부가 다름

| 구성요소 | 책임 |
|:---|:---|
| 프로파일 | 응용 분야별 시스템 기능·메모리 모델 범위 결정 |
| 실행 상태 | 레지스터 폭·명령어 규칙으로 소프트웨어 이진 형식 결정 |
| **예외 수준** | 앱·OS·가상화·보안 펌웨어의 권한 계층 분리 |
| **TrustZone** | 보안·비보안 자원의 물리 접근 경계 분리 |
| 벡터 확장 | SIMD·ML 워크로드의 데이터 병렬 처리 |

#### 한줄 요약
- Arm은 제품 분야를 프로파일로 먼저 나누고, 그 안에서 실행 상태·권한 수준·선택 확장을 조합해 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **예외(Exception)**: 현재 명령어 실행을 중단하고 정의된 처리기로 제어를 옮기는 사건(인터럽트·시스템 호출·오류).
- **벡터 테이블(Vector Table)**: 예외 종류별 처리기 시작 주소를 보관하며, VBAR_ELx 레지스터가 기준 주소를 지정.
- **예외 복귀(Exception Return)**: 저장한 실행 상태를 복원해 예외 발생 전 실행 지점으로 돌아가는 동작.

</details>

```text
실행 중 예외 발생 (인터럽트·시스템 호출·오류)
        │
        ▼
1. 대상 EL 결정: 예외 원인과 현재 EL로 목적 수준 선택
        │
        ▼
2. 상태 저장: 복귀 주소·PSTATE를 EL 전용 레지스터에 저장
        │
        ▼
3. 벡터 분기: VBAR_ELx 기준 예외 종류별 처리기 진입
        │
        ▼
4. 예외 복귀: 저장 상태 복원 후 이전 EL·실행 지점 재개
```

**동작 원리**

1. **대상 EL 결정**: 예외 원인과 현재 EL로 권한 수준 결정
2. **상태 저장**: 복귀 주소와 PSTATE를 목적 EL 레지스터에 저장
3. **벡터 분기**: VBAR_ELx 기준 예외 종류별 처리기 진입
4. **예외 복귀**: ERET 명령으로 상태 복원 후 이전 실행 재개

#### 한줄 요약
- Arm 예외는 현재 권한에서 더 높은 권한의 처리기로 올라가 작업을 마친 뒤, 저장했던 상태를 되돌려 이전 자리로 돌아오는 구조다.

## Ⅴ. 종류 및 비교

| Arm 프로파일 | A-profile | R-profile | M-profile |
|:---|:---|:---|:---|
| 적용 기준 | 범용 OS·가상화·고성능 처리 요구 | 결정적 실시간 응답 필수 | 저전력·소형 제어 장치 |
| 핵심 특징 | **예외 수준** EL0~EL3·MMU·가상화 | 결정적 응답 보장·MPU 기반 보호 | 단순 예외·**M-profile TrustZone** |
| 한계 | 전력·면적·소프트웨어 스택 복잡도 | 범용 OS·가상화 기능 제약 | 고성능·가상화 기능 제약 |

#### 한줄 요약
- OS와 서버 기능이 필요하면 A-profile, 정해진 시간 안의 제어가 핵심이면 R-profile, 작고 저전력이면 M-profile을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **런타임 기능 탐지(Runtime Feature Detection)**: 실행 중 프로세서가 지원하는 확장을 ID 레지스터로 확인해 코드 경로를 결정하는 방식.
- **동적 전압·주파수 조절(Dynamic Voltage and Frequency Scaling, DVFS)**: 부하·온도에 따라 전압과 주파수를 조절하는 전력 관리 기법.
- **최소 권한 원칙(Principle of Least Privilege)**: 코드가 동작에 필요한 최소 EL·자원 접근만 갖도록 설계하는 보안 원칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지원 확장 없는 장치에서 명령어 실행 실패 | **런타임 기능 탐지**·대체 코드 경로 제공 | 장치별 실행 호환성 확보 |
| 특권 코드가 과도한 EL로 자원 접근 | **최소 권한 원칙**·EL 경계 검증 | 취약점 영향 범위 축소 |
| 고부하·고온에서 전력·성능 한계 충돌 | **DVFS** 정책·열 설계 시험 | 전력 한도 내 안정 동작 확보 |
| 프로파일과 OS 기능 요구 불일치 | 프로파일별 예외·메모리 기능 사전 검증 | 제품 요구와 ISA 기능 정합성 확보 |

#### 한줄 요약
- Arm 제품은 지원 확장과 권한 경계, 전력 제어를 실제 장치와 OS 요구에 맞춰 함께 검증해야 한다.

## Ⅶ. 결론

- 범용 OS는 **A-profile**, 실시간 제어는 **R-profile**, 초저전력은 M-profile 선택

#### 한줄 요약
- Arm 선택은 코어 이름보다 제품이 OS를 돌릴지, 정해진 시간 안에 제어할지, 얼마나 작은 전력으로 동작할지에서 출발한다.
