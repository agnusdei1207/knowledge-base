## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm 아키텍처(Arm Architecture)**: 로드·스토어 명령어와 권한, 예외, 보안 동작을 정의하는 프로세서 아키텍처 계열입니다.
- **프로파일(Profile)**: 적용 분야에 따라 Arm 기능 집합과 시스템 모델을 구분한 아키텍처 분류입니다.
- **실행 상태(Execution State)**: 레지스터 폭과 명령어 실행 규칙을 정하는 프로세서 상태입니다.

</details>

- 정의/개념: 프로파일·실행 상태·권한 규격을 갖는 **로드/스토어 ISA**
- 배경/필요성: 전력 제약, 실시간성, 범용 OS 요구의 설계 분리

#### 한줄 요약

- Arm은 같은 명령어 계열 안에서도 휴대기기, 실시간 제어, 단순 장치에 맞춰 구조와 권한 기능을 다르게 구성합니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **예외 수준(Exception Level, EL)**: 시스템 소프트웨어의 권한을 분리하는 Arm A-profile의 실행 단계입니다.
- **TrustZone**: 보안 상태와 비보안 상태를 분리해 자원 접근을 통제하는 Arm 보안 아키텍처입니다.
- **벡터 확장(Vector Extension)**: 하나의 명령어로 여러 데이터 요소를 처리하도록 연산 폭을 확장하는 기능입니다.

</details>

- 메모리 접근을 분리하는 **로드/스토어 ISA**
- 시스템 소프트웨어를 나누는 **예외 수준**
- 보안·벡터 기능을 조합하는 **확장형 설계**

#### 한줄 요약

- Arm은 연산을 단순한 메모리 규칙으로 처리하고, 권한과 보안, 병렬 연산 기능을 필요에 따라 더하는 구조입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **A-profile(Application Profile)**: 범용 운영체제와 가상화를 지원하는 Arm 프로파일입니다.
- **R-profile(Real-Time Profile)**: 예측 가능한 응답 시간이 필요한 실시간 제어용 Arm 프로파일입니다.
- **M-profile(Microcontroller Profile)**: 작은 임베디드 장치와 저전력 제어용 Arm 프로파일입니다.
- **AArch64**: 64비트 일반 목적 레지스터와 실행 규칙을 제공하는 Arm 실행 상태입니다.

</details>

```text
[Arm 아키텍처]
├─ 프로파일
│  ├─ A-profile
│  ├─ R-profile
│  └─ M-profile
├─ 실행 상태
│  └─ AArch64
├─ 권한 모델
│  └─ 예외 수준
└─ 선택 확장
   ├─ TrustZone
   └─ 벡터 확장
```

| 구성요소 | 책임 |
|:---|:---|
| 프로파일 | 적용 분야별 시스템 기능 범위 정의 |
| 실행 상태 | 레지스터 폭과 명령어 규칙 정의 |
| 예외 수준 | 앱·OS·가상화 계층의 권한 분리 |
| TrustZone | 보안·비보안 자원의 접근 경계 분리 |
| 벡터 확장 | 데이터 병렬 연산 기능 제공 |

#### 한줄 요약

- Arm은 제품 분야를 프로파일로 먼저 나누고, 그 안에서 실행 상태와 권한, 확장을 조합합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **예외(Exception)**: 현재 명령어 실행을 중단하고 정의된 처리기로 제어를 옮기는 사건입니다.
- **벡터 테이블(Vector Table)**: 예외 종류별 처리기 시작 주소를 보관한 표입니다.
- **예외 복귀(Exception Return)**: 저장한 실행 상태를 복원해 예외 발생 지점으로 돌아가는 동작입니다.

</details>

```text
[1. 예외 발생]
          │
          ▼
[2. 대상 권한 수준 결정]
          │
          ▼
[3. 상태 저장과 벡터 분기]
          │
          ▼
[4. 처리 후 예외 복귀]
```

동작 원리:

1. 예외 발생: 인터럽트, 시스템 호출, 오류에 따른 실행 전환
2. 대상 권한 수준 결정: 예외 원인과 현재 권한에 맞는 EL 선택
3. 상태 저장과 벡터 분기: 복귀 정보 저장 뒤 벡터 테이블의 처리기 실행
4. 처리 후 예외 복귀: 처리 결과 반영 뒤 저장 상태로 이전 실행 재개

#### 한줄 요약

- Arm의 권한 모드는 문제가 생기거나 OS 도움이 필요할 때, 현재 작업을 저장하고 더 높은 권한의 처리기로 넘긴 뒤 안전하게 돌아오게 합니다.

## Ⅴ. 종류 및 비교

| Arm 프로파일 | A-profile | R-profile | M-profile |
|:---|:---|:---|:---|
| 적용 기준 | 범용 OS·가상화·고성능 처리 | 예측 가능한 실시간 응답 | 저전력 제어와 작은 장치 |
| 핵심 특징 | 풍부한 권한 모델과 메모리 관리 | 결정적 응답과 실시간 제어 | 단순한 예외 처리와 작은 면적 |
| 한계 | 전력·면적·소프트웨어 복잡도 | 범용 OS 기능의 제약 | 가상화·고성능 기능의 제약 |

#### 한줄 요약

- 앱과 서버 기능이 필요하면 A-profile, 정해진 시간 안의 제어가 중요하면 R-profile, 작은 장치면 M-profile을 고릅니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **런타임 기능 탐지(Runtime Feature Detection)**: 실행 중인 프로세서의 지원 확장을 확인해 코드 경로를 정하는 방식입니다.
- **동적 전압·주파수 조절(Dynamic Voltage and Frequency Scaling, DVFS)**: 부하와 온도에 맞춰 전압과 주파수를 조절하는 전력 관리 기법입니다.
- **최소 권한 원칙(Principle of Least Privilege)**: 작업에 필요한 최소 권한만 부여하는 보안 설계 원칙입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특화 확장 미지원 장치에서 명령 실행 실패 | 런타임 기능 탐지와 대체 코드 제공 | 장치별 실행 호환성 확보 |
| 특권 코드가 넓은 권한으로 자원 접근 | 최소 권한 원칙과 EL 경계 검증 | 취약점 영향 범위 축소 |
| 고부하·고온에서 성능과 전력 한계 충돌 | DVFS 정책과 열 설계 시험 | 전력 한도 내 안정 동작 확보 |
| 프로파일과 OS 기능 요구가 불일치 | 프로파일별 예외·메모리 기능 사전 검증 | 제품 요구와 ISA 기능 정합성 확보 |

#### 한줄 요약

- Arm 제품은 지원 확장과 권한 경계, 전력 제어를 실제 장치와 OS 요구에 맞춰 같이 검증해야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **시스템 온 칩(System on Chip, SoC)**: 프로세서, 메모리 제어, 입출력, 가속기를 하나의 칩에 통합한 시스템입니다.

</details>

- 범용 OS·가상화·**SoC** 통합 요구가 우선이면 A-profile을, 예측 가능한 시간 응답과 저전력이 우선이면 R-profile 또는 M-profile을 선택하고 예외·확장 지원 범위를 확정

#### 한줄 요약

- Arm 선택은 코어 이름보다 제품이 운영체제를 돌릴지, 정해진 시간 안에 제어할지, 얼마나 작은 전력으로 동작할지에서 출발합니다.
