## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm 아키텍처(Arm Architecture)**: 로드·스토어 기반 ISA와 용도별 A/R/M 프로파일을 제공하는 프로세서 표준.
- **프로파일(Profile)**: 범용 연산(A-Profile), 실시간 제어(R-Profile), 마이크로컨트롤러(M-Profile) 등 도메인별 하드웨어 기능과 메모리 시스템을 특화한 Arm 아키텍처 분류 체계.
- **실행 상태(Execution State)**: 64비트 레지스터 및 가상 주소 공간을 사용하는 AArch64와 32비트 레거시 호환을 지원하는 AArch32 동작 모드.

</details>

- 정의/개념: 로드·스토어 기반의 고효율 RISC 명령어 세트를 바탕으로 응용 분야별 특화 **프로파일**(A/R/M)과 다단계 **예외 수준**(EL0~EL3) 기반 하드웨어 격리를 제공하는 프로세서 아키텍처 표준
- 배경/필요성: 단일 규격으로는 고성능 OS 구동, 차량·산업용 실시간 제어, 초저전력 IoT 마이크로컨트롤러의 상충되는 하드웨어 요구를 단일 메모리 관리 체계로 수용할 수 없어 공통 RISC 코어를 도메인별 프로파일로 세분화

#### 한줄 요약
- Arm은 고효율 RISC 코어를 기반으로 A(애플리케이션), R(실시간), M(마이크로컨트롤러) 3대 프로파일과 EL0~EL3 권한 계층을 제공하여 전 영역을 커버한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **예외 수준(Exception Level, EL)**: A-profile에서 EL0~EL3로 애플리케이션·운영체제·하이퍼바이저·보안 펌웨어 권한을 구분하는 모델.
- **TrustZone**: 시스템 자원을 일반 영역과 보안 영역으로 구분하고 접근을 통제하는 Arm 보안 기술.
- **SIMD/벡터 확장**: 128비트 미디어 가속(NEON) 및 가변 벡터 길이 기반 머신러닝·HPC 가속(SVE/SVE2)을 지원하는 데이터 병렬 처리 확장.

</details>

- 엄격한 로드/스토어 원칙: 메모리 접근을 전용 명령어로만 한정하여 코어 데이터패스 단순화 및 파이프라인 효율 극대화
- A-profile 특권 격리: EL0~EL3 **예외 수준**을 통해 사용자 앱, OS 커널, 하이퍼바이저, 보안 모니터 권한을 엄격 분리
- 하드웨어 보안 격리: **TrustZone** 기술을 통해 코어, 메모리, 인터럽트 자원을 일반 영역(Non-Secure)과 보안 영역(Secure)으로 2차원 분리

#### 한줄 요약
- Arm은 명확한 로드/스토어 원칙으로 하드웨어 효율을 높이고, EL0~EL3 권한 모델과 TrustZone으로 시스템 안전성과 가상화 보안을 확립한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **A-profile(Application Profile)**: 가상 메모리(MMU)와 대용량 캐시, 멀티코어 및 하이퍼바이저 가상화를 지원하는 고성능 컴퓨팅용 프로파일(Cortex-A).
- **R-profile(Real-Time Profile)**: MPU·TCM으로 예측 가능한 지연을 지원하는 자동차·통신 제어용 프로파일(Cortex-R).
- **M-profile(Microcontroller Profile)**: 하드웨어 인터럽트 컨트롤러(NVIC)와 결합하여 초저전력 및 빠른 웨이크업에 최적화된 임베디드용 프로파일(Cortex-M).

</details>

```text
[Arm 프로세서 아키텍처]
  │
  ├─ [예외 수준 (EL0 ~ EL3)]
  │     ├─ [EL0 / EL1] (User 앱 / OS 커널)
  │     ├─ [EL2] (Hypervisor 가상화)
  │     └─ [EL3] (Secure Monitor 펌웨어)
  │
  ├─ [TrustZone 격리] (Secure / Non-Secure 분리)
  │
  └─ [Cortex 3대 프로파일]
        ├─ [A-Profile] (고성능 컴퓨팅 / MMU)
        ├─ [R-Profile] (실시간 제어 / MPU·TCM)
        └─ [M-Profile] (초저전력 임베디드 / NVIC)
```

선의 의미: Arm 프로세서의 예외 수준(EL), TrustZone 보안 영역 및 3대 프로파일 계층 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| A-Profile | MMU 기반 가상 메모리와 EL2 하드웨어 가상화를 지원하는 **고성능 연산** 담당 |
| R-Profile | MPU 및 밀결합 메모리(TCM)를 통한 마이크로초 단위 **결정론적 응답** 보장 |
| M-Profile | 하드웨어 NVIC 기반 초저지연 인터럽트 처리 및 **초저전력 대기** 제어 |
| 예외 수준(EL) | 시스템 호출·트랩 발생 시 권한 계층을 전환하고 **실행 권한 격리** 수행 |
| TrustZone | 물리 메모리 및 주변 버스를 하드웨어 레벨에서 암호화·분리하는 **보안 영역** 구축 |

#### 한줄 요약
- Arm 아키텍처는 용도별 3대 프로파일과 4단계 EL 권한 계층, 그리고 TrustZone 하드웨어 격리를 통해 칩 설계의 유연성과 강력한 보안을 제공한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **예외 복귀 레지스터(ELR_ELx / SPSR_ELx)**: 예외 발생 시 복귀할 프로그램 주소(ELR)와 이전 프로세서 상태(SPSR)를 상위 EL 하드웨어가 자동으로 백업하는 특수 레지스터.
- **ERET(Exception Return)**: 상위 EL에서 예외 처리를 완료한 후 SPSR과 ELR을 원자적으로 복원하여 하위 EL의 이전 실행 지점으로 복귀하는 명령어.

</details>

```text
[EL0 사용자 애플리케이션 실행 중 예외(SVC / 인터럽트) 발생]
                            │
                            ▼
1. 하드웨어 상태 백업 및 권한 승격 (SPSR_EL1, ELR_EL1 저장 ➔ EL1 전환)
                            │
                            ▼
2. 벡터 테이블(VBAR_EL1) 진입 및 예외 핸들러 실행
                            │
                            ▼
3. 서비스 완료 및 ERET 명령어 실행 (SPSR/ELR 레지스터 상태 복원)
                            │
                            ▼
[EL0 사용자 애플리케이션 복귀 및 차기 명령어 실행 재개]
```

분기 결과: 예외 원인(시스템 호출 vs 하드웨어 인터럽트)에 따라 벡터 테이블 오프셋이 갈리며, 상태 백업(SPSR/ELR)과 원자적 복원(ERET) 메커니즘을 거쳐 안전하게 복귀함

**동작 원리**

1. **하드웨어 상태 백업 및 권한 승격**: EL0에서 시스템 호출(SVC)이나 외부 인터럽트 발생 시 하드웨어가 현재 PSTATE를 SPSR_EL1에, 복귀 PC를 ELR_EL1에 자동 저장하고 EL1 모드로 승격함
2. **벡터 테이블 진입 및 예외 핸들러 실행**: VBAR_EL1 레지스터가 가리키는 예외 벡터 테이블에서 발생 원인에 매핑된 핸들러 주소로 분기하여 커널 루틴을 실행함
3. **서비스 완료 및 ERET 명령어 실행**: 커널 처리가 완료되면 ERET 명령어를 인가하여 SPSR_EL1과 ELR_EL1의 레지스터 상태를 원자적으로 복원하고 EL0 애플리케이션으로 복귀함

#### 한줄 요약
- 예외 발생 시 하드웨어가 현재 상태와 복귀 주소를 상위 EL 레지스터(SPSR/ELR)에 자동 백업하고, 처리가 끝나면 ERET 명령어로 안전하게 복귀한다.

## Ⅴ. 종류 및 비교

| Arm 프로파일 구분 | A-Profile (Cortex-A) | R-Profile (Cortex-R) | M-Profile (Cortex-M) |
|:---|:---|:---|:---|
| 적용 기준 | **고성능 OS 구동** 및 가상화 서버 요구 | **실시간 제어** 및 결정론적 응답 요구 | **초저전력 배터리** 및 초소형 MCU 요구 |
| 핵심 특징 | MMU 기반 가상 메모리 및 **EL2 가상화** | MPU 및 밀결합 메모리 기반 **실시간성** | NVIC 인터럽트 컨트롤러 및 **초저전력** |
| 한계 | 가상 메모리 페이징으로 지연 변동 발생 | 가상 메모리 부재로 대규모 범용 OS 불가 | 연산 성능 제약 및 고도 가상화 미지원 |

#### 한줄 요약
- 범용 OS와 가상화가 필수면 A-Profile, 엄격한 실시간 응답 보장이면 R-Profile, 배터리 기반 초저전력 제어면 M-Profile을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **밀결합 메모리(Tightly Coupled Memory, TCM)**: R/M-profile에서 캐시를 우회해 예측 가능한 접근 시간을 제공하는 전용 SRAM.
- **인터럽트 지연시간(Interrupt Latency)**: 외부 하드웨어 인터럽트 신호 발생 시점부터 ISR의 첫 번째 명령어가 실행되기까지 소요되는 사이클 수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| A-profile의 가상 메모리 변환 및 캐시 미스로 인한 인터럽트 지연시간 변동 | 실시간 경로에 **R-profile** 코어 및 **TCM** 배치 | 메모리 지연 지터 제거 및 마이크로초 단위 응답 보장 |
| 일반 영역 OS 침해 시 시스템 보안 자산 탈취 위험 | **TrustZone** 및 시큐어 모니터(EL3) 격리 적용 | 하드웨어 레벨의 암호키 및 보안 서비스 무결성 유지 |
| 이종 프로파일(A/R/M) 코어 간 공유 메모리 통신 오버헤드 | 하드웨어 메일박스 및 메모리 배리어 명령어 적용 | 이기종 코어 간 메시지 전달 지연 단축 및 일관성 확보 |

#### 한줄 요약
- 실무 SoC 설계에서는 A-Profile(범용 UI/연산)과 R/M-Profile(실시간/보안 제어)을 TrustZone 및 캐시 인터커넥트로 통합하는 이종 아키텍처를 구성한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **기밀 컴퓨팅 아키텍처(Confidential Compute Architecture, CCA)**: Armv9에서 도입된 하드웨어 기반 메모리 격리 기술로, 하이퍼바이저조차 접근할 수 없는 Realm 영역을 생성하여 기밀 워크로드를 보호하는 구조.
- **SVE2(Scalable Vector Extension 2)**: 벡터 길이를 구현체에 위임하여 128~2048비트까지 유연하게 확장하는 Armv9 SIMD 명령어 확장.

</details>

- 스마트폰·임베디드 표준을 넘어 네오버스 기반 클라우드 데이터센터와 차세대 차량용(Armv9) 플랫폼으로 확장된 성숙 단계에 있으며, **CCA** 및 **SVE2** 벡터 연산 확장을 통해 AI 가속과 보안 격리를 주도하고 있어, 실시간성 보장과 범용 연산 요구를 평가한 A/R/M 코어 혼합 토폴로지와 TrustZone 영역 분할 설계

#### 한줄 요약
- Arm은 A/R/M 3대 프로파일을 통해 임베디드부터 슈퍼컴퓨팅까지 포괄하며, EL 권한 모델과 TrustZone이 엔터프라이즈급 신뢰성을 완성한다.
