## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm 아키텍처(Arm Architecture)**: 저전력 로드•스토어 기반 연산 구조에 다단계 권한 격리와 모듈형 확장을 결합한 산업 표준 규격이다.
- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 하드웨어가 실행하는 기계어 명령, 레지스터 구조 및 권한 모드를 정의하는 인터페이스이다.
- **실행 상태(Execution State)**: 프로세서 코어가 실행할 레지스터 폭 및 기계어 명령어 포맷을 규정하는 동작 모드이다.
- **예외 수준(Exception Level, EL)**: 보안성 강화를 위해 프로세서 권한을 4단계로 계층 격리한 보안 아키텍처이다.
- **선택 명령 확장(Optional Extension)**: 센서, 인공지능, 그래픽 등 특화된 연산을 지원하기 위해 아키텍처에 추가하는 명령어 세트이다.

</details>

- 정의: 저전력 축소 명령어 기반의 연산 구조와 4단계 예외 수준 권한 격리를 규정한 글로벌 표준 **Arm 아키텍처**
- 배경: 단일 특권 구조의 취약점이 전체 시스템으로 확산됨에 따라 하드웨어 기반 계층 격리와 전력 효율성을 확보하기 위함

#### 한줄 요약

- Arm 아키텍처는 저전력 구조를 바탕으로 실행 상태 모드와 4단계 권한 격리 체계를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로드•스토어 구조(Load/Store Architecture)**: 메모리 직접 연산을 배제하고 명시적 명령어만으로 접근하여 연산을 범용 레지스터 내에서 수행하는 특성이다.
- **코어 지식재산권(Core Intellectual Property)**: 팹리스 업체에 즉시 제공되어 시스템 온 칩 합성에 사용 가능한 사전 검증 프로세서 블록이다.
- **마이크로아키텍처(Microarchitecture)**: 사양을 만족시키면서 파이프라인과 캐시를 다르게 구성한 물리적 회로 설계이다.

</details>

- **로드•스토어 구조**를 채택하여 연산 시 메모리 접근 지연을 우회하고 실행 효율을 증대함.
- **실행 상태** 전환과 **예외 수준**을 결합하여 레거시 32비트 호환과 64비트 하드웨어 권한 격리를 동시에 달성함.
- 명령어 규격 라이선스와 사전 완성된 **코어 지식재산권** 형태를 이원화 공급하여 모바일 및 임베디드 시장에 대응함.

#### 한줄 요약

- 로드 스토어 구조와 권한 격리를 기반으로 상용 코어와 지식재산권 라이선싱 모델을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AArch64**: 64비트 범용 레지스터를 지원하는 64비트 실행 상태이다.
- **AArch32**: 기존 32비트 명령어 세트를 구동하며 호환성을 유지하는 실행 상태이다.
- **고정 길이 SIMD 확장(Advanced SIMD)**: 벡터 레지스터를 통해 미디어 및 데이터 병렬 처리를 수행하는 128비트 엔진이다.
- **확장 가능 벡터 확장(Scalable Vector Extension, SVE)**: 하드웨어 구현에 따라 가변 레지스터 폭을 지원하는 벡터 연산 아키텍처이다.
- **레지스터 집합(Register Set)**: 연산 데이터를 고속 적재하는 범용 레지스터와 프로그램 카운터 등의 모음이다.
- **예외 수준 격리(Exception Level Isolation)**: 애플리케이션, 운영체제, 가상화, 보안 모니터로 특권을 구분하는 체계이다.

</details>

```text
[ 프로세서 아키텍처 계층 구조 ]
┌───────────────────────────────────────────────────────────┐
│ 실행 상태 : AArch64 (64-bit)  /  AArch32 (32-bit)         │
├───────────────────────────────────────────────────────────┤
│ 예외 수준 (하드웨어 권한 격리)                            │
│  - EL0 : 애플리케이션                                     │
│  - EL1 : 운영체제 커널                                    │
│  - EL2 : 하이퍼바이저 및 가상화                           │
│  - EL3 : 보안 모니터                                      │
├───────────────────────────────────────────────────────────┤
│ 벡터 및 부동소수점 엔진 : NEON / SVE                      │
└───────────────────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| AArch64 | 64비트 레지스터 및 전용 명령어 실행 |
| AArch32 | 32비트 레거시 **레지스터 집합** 호환 실행 |
| 예외 수준 | 4단계 **예외 수준 격리**를 통한 권한 분리 |
| 벡터 엔진 | 고정 및 가변 폭의 벡터 병렬 연산 수행 |

#### 한줄 요약

- 실행 상태, 권한 격리, 벡터 확장 엔진이 아키텍처의 핵심을 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프로세서 상태(Processor State, PSTATE)**: 조건 플래그, 인터럽트 마스크, 현재 예외 수준 정보를 보관하는 CPU 상태 필드이다.
- **예외 링크 레지스터(Exception Link Register)**: 예외 처리 완료 후 원본 복귀를 위해 이전 카운터 주소를 저장하는 레지스터이다.
- **저장 프로그램 상태 레지스터(Saved Program Status Register)**: 예외 진입 순간의 프로세서 상태 값을 보관하는 레지스터이다.
- **벡터 기준 주소 레지스터(Vector Base Address Register)**: 타깃 예외 수준에 대응하는 예외 벡터 테이블의 시작 주소를 지시하는 레지스터이다.
- **예외 처리기(Exception Handler)**: 하드웨어 트랩, 시스템 콜, 인터럽트를 처리하는 커널 루틴이다.
- **예외 복귀(Exception Return)**: 복원 저장된 상태와 주소로 이전 실행 환경에 복귀하는 특권 명령어이다.

</details>

```text
[ 소프트웨어 실행 중 ]
         │
         ▼ 시스템 콜 / 인터럽트 발생
[ 하드웨어 트랩 ]
 1. 프로세서 상태 -> 저장 프로그램 상태 레지스터 보관
 2. 복귀 주소 -> 예외 링크 레지스터 보관
 3. 벡터 기준 주소 레지스터 참조 ──> 예외 처리기 진입
         │
         ▼
[ 예외 처리기 실행 ]
         │
         ▼ 예외 복귀 명령어 실행
[ 프로세서 상태 복원 ]
 레지스터 복원 ──> 이전 실행 재개
```

### 동작 원리

1. 상태 저장: 예외 발생 시 코어 하드웨어가 현재 **프로세서 상태**와 복귀 주소를 **저장 프로그램 상태 레지스터** 및 **예외 링크 레지스터**에 자동 백업함.
2. 벡터 오프셋 분기: **벡터 기준 주소 레지스터**에 기록된 베이스 주소에 오프셋을 가산하여 예외 벡터 주소를 결정함.
3. 예외 처리: 지정된 **예외 처리기**로 점프하여 커널 서비스 및 인터럽트 처리를 수행함.
4. 상태 복원: 처리 완료 후 **예외 복귀** 명령을 실행하여 이전 실행 흐름으로 복귀함.

#### 한줄 요약

- 예외 발생 시 상태를 특수 레지스터에 보관하고 지정된 핸들러를 실행한 뒤 원본 상태로 복귀한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시스템 온 칩(System on Chip)**: 코어, 메모리 컨트롤러, 통신 모듈을 하나의 반도체에 집적한 시스템이다.
- **x86-64 아키텍처(x86-64 Architecture)**: 복합 명령어 구조 기반의 64비트 범용 운영체제 및 서버 표준 규격이다.
- **레거시 부담(Legacy Overhead)**: 과거 가변 길이 복합 기계어를 지원하기 위한 하드웨어 복잡성이다.
- **가변 길이 명령•호환 모드(Variable-Length Compatibility Mode)**: 1바이트부터 15바이트의 가변 비트를 해석하여 호환성을 유지하는 방식이다.
- **재빌드•변환(Rebuild & Translation)**: 타 아키텍처 바이너리를 실행하기 위해 재컴파일이나 동적 번역을 수행하는 작업이다.

</details>

| 비교 항목 | Arm 아키텍처 | x86-64 아키텍처 |
|:---|:---|:---|
| 성격 | 고효율 **로드•스토어 구조** 축소형 | 가변 길이 기반 복합형 |
| 모드 | 다단계 권한 격리 및 실행 상태 | 링 보호 및 보호 모드 |
| 생태계 | **시스템 온 칩** 및 전력 제약 기기 중심 | 고성능 PC 및 서버 중심 |
| 호환성 | **재빌드•변환** 작업 필수 요구 | 기존 누적 바이너리 하위 호환 |
| 오버헤드 | 정형 인코딩으로 프런트엔드 간소화 | 하위 호환에 따른 막대한 **레거시 부담** |

#### 한줄 요약

- Arm은 모바일 기기의 저전력 효율성에 강점을 가지며, x86-64는 고성능과 레거시 호환성에 강점이 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **네이티브 라이브러리(Native Library)**: 작성되어 특정 기계어로 컴파일된 공유 라이브러리이다.
- **런타임 기능 탐지(Runtime Feature Detection)**: 실행 중 시스템 레지스터를 조회하여 벡터 확장 지원 여부를 동적으로 판별하는 기술이다.
- **최소 권한(Least Privilege)**: 보안 강화를 위해 애플리케이션은 사용자 권한으로 커널은 시스템 권한으로 격리하는 원칙이다.
- **대체 코드(Fallback Code)**: 최신 명령어를 지원하지 않는 구형 기기를 위해 마련된 범용 표준 코드 블록이다.
- **전력 벤치마크(Power Benchmark)**: 목표 장비의 초당 전력 소모량과 성능 지수를 실측하여 평가하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **네이티브 라이브러리** 이전 시 호환성 충돌 | 타깃 빌드 체계 및 동적 이진 변환 체계 구축 | 이종 아키텍처 마이그레이션 오류 해결 |
| 불필요한 특권 권한 점유로 시스템 안정성 훼손 | **최소 권한** 원칙 준수 및 모드 간 인터페이스 통제 | 사이드 채널 공격 및 보안 침해 파급력 차단 |
| 신규 벡터 명령어 실행 시 구형 단말 충돌 | **런타임 기능 탐지** 적용 및 **대체 코드** 제공 | 단말 세대에 구애받지 않는 실행 안정성 |
| 고부하 작업 중 발열 및 스로틀링 발생 | **전력 벤치마크** 기반 동적 주파수 전압 제어 | 시스템 전력 한도 내 최고 성능 유지 |

#### 한줄 요약

- 호환성 구축, 최소 권한 원칙 적용, 기능 탐지 및 전력 벤치마크로 안정성과 성능을 최적화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **전력 효율(Power Efficiency)**: 연산 단위당 소모되는 주울 및 와트 전력 소비 비율이다.
- **아키텍처 선택 기준(Architecture Selection Criteria)**: 대상 기기의 전력 제약과 컴퓨팅 성능을 종합 평가하는 지표이다.

</details>

- **아키텍처 선택 기준**에 따라 전력 효율과 집적도가 우선이면 **Arm 아키텍처**를 선택

#### 한줄 요약

- 시스템의 목적과 전력 제약을 최우선으로 고려하여 아키텍처를 선정해야 한다.
