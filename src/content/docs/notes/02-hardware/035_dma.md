## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 제어기가 메인 메모리와 주변장치 사이의 데이터 전송을 주도하는 기술.
- **복사 오버헤드(Copy Overhead)**: CPU 코어가 직접 레지스터를 통해 데이터를 한 바이트씩 복사하면서 발생하는 연산력 낭비.
- **버스 마스터(Bus Master)**: CPU 대신 시스템 버스의 제어권을 획득하여 읽기·쓰기 트랜잭션을 주도할 수 있는 권한을 가진 장치.

</details>

- 정의/개념: CPU 개입 없이 **전용 DMA 컨트롤러**가 주기억장치와 입출력 장치 간 대용량 데이터를 직접 전송하는 하드웨어 제어 기법
- 배경/필요성: CPU가 장치 데이터를 단위별로 복사하면 전송량에 비례해 **명령 실행·인터럽트 부담** 증가

#### 한줄 요약
- CPU 대신 전용 하드웨어가 메모리와 장치 사이에서 대용량 데이터를 직접 주고받는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사이클 스틸링(Cycle Stealing)**: DMA가 CPU의 버스 유휴 사이클을 가로채 1워드씩 전송하는 모드.
- **버스트 모드(Burst Mode)**: 버스를 한 번 선점한 후 전체 블록을 연속해서 고속 전송하는 모드.
- **산란-집적(Scatter-Gather)**: 물리적으로 불연속한 여러 메모리 버퍼를 한 번의 DMA 명령으로 연속 전송하는 기법.

</details>

- **CPU 오프로딩**으로 데이터 복사 루프를 제거하고 설정·완료 처리만 CPU에 유지
- **버스 마스터링**을 통해 독자적 읽기·쓰기 트랜잭션 주도
- 전송 완료 시에만 인터럽트를 발생시켜 CPU 개입 최소화

#### 한줄 요약
- CPU는 전송 시작과 끝만 관여하고, 실제 데이터 이동은 DMA 제어기가 버스를 획득해 처리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주소 레지스터(Address Register)**: 전송할 메모리의 시작 물리 주소를 보관하고 전송마다 자동 증가하는 레지스터.
- **카운트 레지스터(Count Register)**: 전송할 총 바이트(또는 워드) 수를 저장하고 전송 시마다 감소하는 레지스터.

</details>

```text
[ 호스트 CPU ] ───────┐
                      │ (버스 요청 BR / 버스 승인 BG)
                      ▼
┌───────────────────────────────────────────────┐
│ DMA 컨트롤러 (DMAC)                           │
│  ├─ 메모리 주소 레지스터 (MAR)                │
│  ├─ 바이트 카운트 레지스터 (BCR)              │
│  ├─ 제어 및 상태 레지스터 (CSR)               │
│  └─ 버스 요청/승인 중재 회로                  │
└─────────────────────┬─────────────────────────┘
                      │ (시스템 주소/데이터 버스 점유)
      ┌───────────────┴───────────────┐
      ▼                               ▼
 [ 메인 메모리 (DRAM) ] <──────> [ 고속 주변장치 (NVMe/NIC) ]
```

선의 의미: 상단은 CPU와 DMAC 간 버스 제어선; 하단은 메모리와 주변장치 간 직접 데이터 전송 경로

| 구성요소 | 책임 |
|:---|:---|
| 메모리 주소 레지스터 | 전송 대상 시작 메모리 주소 저장 및 전송마다 주소 갱신 |
| 바이트 카운트 레지스터 | 전송 잔여 바이트 수 관리 및 0 도달 시 완료 인터럽트 트리거 |
| 제어/상태 레지스터 | 전송 방향(읽기/쓰기), 전송 모드 설정 및 상태 플래그 보관 |
| 버스 중재 로직 | CPU에 버스 요청(BR)을 보내고 버스 승인(BG) 신호 획득 |

#### 한줄 요약
- 주소와 카운트 레지스터가 전송 위치와 크기를 관리하고, 제어 로직이 버스를 획득해 전송을 지휘한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **버스 요청(Bus Request, BR)**: DMA 제어기가 CPU에 버스 사용 권한을 넘겨달라고 요청하는 신호.
- **버스 승인(Bus Grant, BG)**: CPU가 현재 버스 사이클을 비우고 DMA에 버스 제어권을 위임하는 신호.

</details>

```text
CPU: DMA 전송 설정 (시작주소·카운트·방향)
      │
      ▼
1. DMA 버스 요청
      │
      ▼
2. CPU 버스 승인
      │
      ▼
3. 직접 데이터 전송
      │
      ▼
4. 완료 및 버스 반환
```

**동작 원리**

1. **DMA 버스 요청**: 설정을 마친 DMAC가 BR 신호로 버스 제어권 요청
2. **CPU 버스 승인**: CPU가 현재 전송을 마친 뒤 BG 신호 반환
3. **직접 데이터 전송**: DMAC가 주소·제어 신호를 발생시켜 메모리와 장치 사이의 블록 이동
4. **완료 및 버스 반환**: 잔여량이 없으면 제어권을 반환하고 CPU에 완료 인터럽트 통지

#### 한줄 요약
- CPU가 설정을 마치면 DMA가 버스를 빌려 데이터를 직접 옮기고, 끝나면 버스를 돌려주며 인터럽트를 건다.

## Ⅴ. 종류 및 비교

| DMA 전송 모드 | 버스트·블록 모드 | 사이클 스틸링 | 디맨드 모드 |
|:---|:---|:---|:---|
| 적용 기준 | 대용량 연속 전송 처리량 우선 | CPU 메모리 접근 지연 제한 | 장치 준비 신호에 맞춘 가변 전송 |
| 핵심 특징 | 버스를 연속 점유해 블록 완료 | 짧은 버스 점유 후 CPU에 반환 | 장치 요청 신호 활성 동안 전송 지속 |
| 한계 | CPU 메모리 접근 장시간 차단 | 잦은 중재·반환 오버헤드 | 장치 지연 중 버스 점유 가능 |

#### 한줄 요약
- 연속 처리량은 버스트·블록 모드, CPU 응답성은 사이클 스틸링, 장치 준비 속도 연동은 디맨드 모드가 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IOMMU(Input-Output Memory Management Unit)**: DMA 장치가 사용하는 가상 주소를 물리 주소로 변환하고 메모리 보호를 수행하는 장치.
- **캐시 정리·무효화(Cache Clean/Invalidate)**: 장치가 메모리를 읽기 전 CPU의 더티 데이터를 반영하고, 장치가 쓴 뒤 CPU의 오래된 사본을 폐기하는 작업.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DMA 전송 데이터와 CPU 캐시 불일치 | 방향별 **캐시 정리·무효화** 또는 하드웨어 일관성 사용 | CPU·장치의 최신 버퍼 관찰 일치 |
| 버스트 모드로 인한 CPU 메모리 기아 | **사이클 스틸링** 혼용 및 최대 점유 시간 제한 | CPU 연산 지연 방지 및 응답성 유지 |
| 물리적으로 흩어진 페이지의 전송 복잡도 | **산란-집적(Scatter-Gather)** 체인 리스트 적용 | 연속 메모리 할당 실패 방지 및 전송 자동화 |
| 악의적 장치의 비인가 메모리 접근 | **IOMMU** 기반 주소 변환 및 권한 격리 적용 | 가상화 환경 보호 및 메모리 보안성 강화 |

#### 한줄 요약
- 캐시 무효화로 일관성을 잡고, 산란-집적으로 단편화를 극복하며, IOMMU로 장치 메모리 접근을 격리한다.

## Ⅶ. 결론

- 대용량 연속 전송은 **버스트 DMA**, CPU 응답성 제약이 크면 **사이클 스틸링**을 선택하고, 현대 시스템에서는 IOMMU 격리와 일관성 지원 여부에 맞춰 캐시 유지보수를 함께 결정

#### 한줄 요약
- 데이터 크기와 실시간 응답 요구에 맞춰 전송 모드를 선택하고, IOMMU와 캐시 일관성 대책을 함께 갖춰야 한다.
