## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **DMA**: Direct Memory Access, 전용 엔진이 장치와 메모리 사이를 직접 전송하는 기법
- **CPU**: Central Processing Unit, 명령을 실행하는 중앙 처리 장치
- **I/O**: Input/Output, 호스트와 장치 사이의 입출력
- **CPU 복사 비용**: CPU가 I/O 데이터를 직접 옮기며 소비하는 시간과 대역폭

</details>

- 정의/개념: 전용 엔진이 장치와 메모리 사이의 블록을 직접 전송해 **CPU 개입을 줄이는 기법**
- 배경/필요성: 대량 I/O의 직접 복사로 **CPU 처리 시간과 메모리 대역폭 소모**

#### 한줄 요약

- CPU가 주소•길이•방향을 설정하면 DMA 엔진이 장치와 메모리 사이의 데이터를 직접 전송한다

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **버스 마스터**: 인터커넥트에서 메모리 읽기•쓰기 트랜잭션을 직접 시작하는 주체
- **전송 디스크립터**: 전용 전송 엔진이 사용할 주소•길이•방향을 기록한 작업 명세
- **분산 수집**: 흩어진 여러 메모리 버퍼를 하나의 디스크립터 목록으로 전송하는 방식

</details>

- 큰 블록에서 설정 비용을 상쇄하는 **CPU 복사 절감 효과**
- DMA 컨트롤러의 **버스 마스터** 전송
- 비연속 버퍼를 한 작업으로 전송하는 **분산 수집**

#### 한줄 요약

- 대용량•분산 버퍼에서 **CPU 복사 비용** 절감

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **DMA 드라이버**: 전송 명세와 엔진 시작•완료•오류를 처리하는 소프트웨어
- **DMA 컨트롤러**: 버스 마스터로 장치와 주기억장치 사이의 블록을 옮기는 회로
- **주기억장치 버퍼**: 실제 데이터와 DMA 디스크립터를 장치가 접근하도록 보관하는 영역

</details>

```text
                       [CPU•DMA 드라이버]
                                |
[I/O 장치] ----- [DMA 컨트롤러] ----- [주기억장치]
```

선의 의미: 선은 DMA 컨트롤러를 중심으로 제어 경계와 장치•메모리 데이터 경계가 결합되는 정적 연결 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| CPU•DMA 드라이버 | 전송 명세•**시작•완료 처리** |
| DMA 컨트롤러 | 장치•메모리 **블록 전송** |
| I/O 장치 | 데이터 **출발지•목적지** 제공 |
| 주기억장치 | 데이터•**디스크립터 보관** |

#### 한줄 요약

- CPU가 전송 명세를 제출하면 DMA 컨트롤러가 장치와 메모리 사이의 블록을 옮긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **버퍼 매핑**: 메모리 버퍼를 장치 주소 공간에 연결하고 접근 권한을 설정하는 작업
- **IOMMU**: Input-Output Memory Management Unit, DMA 주소를 변환•격리하는 하드웨어
- **전송 완료 통지**: 블록 이동 완료를 CPU 드라이버에 알리는 인터럽트나 큐 상태

</details>

```text
                      [CPU I/O 요청]
                              |
                 1. IOMMU 버퍼 매핑•권한 설정
                              |
                 2. 전송 디스크립터 등록•시작
                              |
                       [DMA 컨트롤러]
                              |
              +--------------------------------+
              | 반복: 디스크립터 잔여 블록    |
              | 3. 장치 주소 변환•접근 판정  |
              | 4. 장치•메모리 블록 전송     |
              +--------------------------------+
                              |
                       [완료 상태 기록]
                              |
                    [완료 통지•버퍼 인계]
```

**동작 원리**

- **1. IOMMU 버퍼 매핑•권한 설정**: 장치 접근 범위 제한
- **2. 전송 디스크립터 등록•시작**: 주소•길이•방향 지정
- **3. 장치 주소 변환•접근 판정**: 물리 주소와 권한 확인
- **4. 장치•메모리 블록 전송**: CPU 복사 없이 데이터 이동

#### 한줄 요약

- CPU는 전송 디스크립터를 제출하고 DMA 엔진은 장치와 메모리 사이의 전송을 수행한다

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **인터럽트 입출력(Interrupt Input/Output, 인터럽트 I/O)**: 장치가 준비될 때마다 중앙 처리 장치(Central Processing Unit, CPU)에 알리고 CPU가 데이터 전송을 수행하는 방식
- **프로그램 입출력(Programmed Input/Output, 프로그램 I/O)**: CPU가 장치 상태를 반복 확인하면서 데이터까지 직접 옮기는 방식
- **설정 비용**: 전송 디스크립터•주소 매핑•동기화를 준비하는 데 드는 고정 처리 시간

</details>

| I/O 방식 | DMA | 인터럽트 I/O | 프로그램 I/O |
|:---|:---|:---|:---|
| 적용 기준 | 대용량•연속•분산 블록 | 비정기 소량 이벤트 | 매우 짧고 단순한 I/O |
| 핵심 특징 | 전용 엔진의 **블록 직접 전송** | 인터럽트마다 **CPU 전송** | 대기 CPU의 **직접 전송** |
| 한계 | 설정•동기화•**디스크립터 관리** | 인터럽트•**문맥 전환** | 바쁜 대기•**CPU 복사** |

> 요약: 대량은 DMA, 소량은 인터럽트 I/O

#### 한줄 요약

- 대량은 **DMA**, 소량 사건은 인터럽트 I/O

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **캐시 clean**: CPU 수정분을 메모리에 반영하는 동작
- **캐시 invalidate**: DMA가 바꾼 메모리의 오래된 캐시 사본을 버리는 동작
- **버퍼 소유권**: CPU와 장치 중 누가 버퍼를 읽거나 쓸 수 있는지 나타내는 접근 상태
- **메모리 장벽**: 버퍼 데이터와 장치 레지스터 접근이 정해진 순서로 관측되도록 보장하는 명령
- **비휘발성 메모리 익스프레스(Non-Volatile Memory Express, NVMe)**: DMA로 저장장치와 호스트 메모리 사이를 전송하는 인터페이스

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비일관 캐시에서 CPU•장치 값 불일치 | 전송 방향별 **clean•invalidate** 와 메모리 장벽 적용 | **최신 데이터** 보장 |
| 완료 전 CPU가 버퍼를 재사용 | **소유권 상태** 와 완료 동기화•참조 수명 명시 | **동시 접근•손상** 방지 |
| 잘못된 디스크립터로 임의 메모리 접근 | **IOMMU 권한•범위** 검증과 오류 로그 적용 | **DMA 격리** 강화 |
| 대용량 버스트의 버스 경합•부분 실패 | 전송 크기•우선순위 조정과 잔여 길이 기반 **재시도** | **대역폭 공정성•복구성** 향상 |

> 사례: NVMe의 DMA 버퍼 접근 범위를 제한하는 **IOMMU**

#### 한줄 요약

- **IOMMU•버퍼 소유권** 으로 침범과 재사용 손상 방지

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **대용량 블록 전송**: 설정 비용보다 CPU 복사 절감 이득이 큰 데이터 이동
- **비정기 소량 I/O**: DMA 준비보다 인터럽트 처리가 간단한 소량 작업

</details>

- 대용량은 **DMA**, 비정기 소량은 **인터럽트 I/O** 선택

#### 한줄 요약

- 전송량이 설정 비용을 넘을 때 DMA와 IOMMU 적용
