## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access)**: 초고속 주변장치와 메인 메모리 간에 대용량 데이터를 전송할 때, 중앙처리장치 코어를 우회하여 전용 하드웨어 제어기가 메모리 제어권을 획득해 복사를 대행하는 고속 통제 방식이다.
- **복사 비용(Copy Overhead)**: 프로세서 코어가 직접 레지스터를 사용해 바이트 단위로 데이터를 맴돌며 복사하느라 다른 중요한 연산 스레드를 구동하지 못하고 낭비하는 치명적인 연산력 손실 지표이다.
- **버스 마스터(Bus Master)**: 중앙처리장치를 대신하여 시스템 주소 버스와 데이터 버스의 제어권을 스스로 획득하고 트랜잭션을 능동적으로 시작 및 통제할 수 있는 권한을 부여받은 전용 제어 장치이다.

</details>

- 정의: 중앙처리장치 개입 없이 전용 하드웨어 제어기가 **버스 마스터** 권한을 획득하여 주변장치와 메인 메모리 간 블록 데이터를 쏟아붓듯 직접 전송하는 **직접 메모리 접근** 기술
- 배경: 대용량 입출력 시 코어가 복사 작업을 직접 전담하면 막대한 **복사 비용**이 발생하여 전체 시스템 성능이 얼어붙으므로, 단순 무식한 데이터 이동을 전용 하드웨어로 분리하기 위함

#### 한줄 요약

- 연산의 천재인 중앙처리장치가 단순 짐 나르기에 시간을 허비하지 않도록, 전문 짐꾼인 하드웨어 제어기가 버스 권한을 넘겨받아 데이터를 직접 메모리로 옮기는 무지연 전송 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **전송 디스크립터(Transfer Descriptor)**: 출발지 주소, 목적지 주소, 전송 길이, 제어 플래그 등 제어기가 데이터를 퍼 나르기 위해 필요한 작업 지시서 정보를 담은 커널 메모리 구조체이다.
- **분산 수집(Scatter-Gather DMA)**: 메인 메모리 상에 파편화되어 흩어져 있는 여러 조각의 버퍼들을 하나의 디스크립터 체인으로 엮어, 단 한 번의 장치 기동으로 연속 전송을 완수하는 고급 기법이다.
- **사이클 훔치기(Cycle Stealing)**: 프로세서가 메모리 버스를 사용하지 않는 찰나의 유휴 시간을 노려 제어기가 버스 제어권을 살짝 뺏어 쓰고 돌려주는 방식으로, 방해를 최소화하며 데이터를 쪼개 나르는 전송 모드이다.

</details>

- 중앙처리장치는 **전송 디스크립터**라는 지시서의 설정 및 예외만 통제하고 묵직한 데이터 이동은 제어기가 전담 수행함.
- 물리 메모리의 파편화 문제를 극복하기 위해, 여러 흩어진 버퍼를 체인으로 연결해 묶어서 한 번에 나르는 **분산 수집** 방식을 기본 지원함.
- 버스 제어권 획득 전략에 따라 블록 전체를 통째로 점유하는 모드와 프로세서 유휴 시간을 잘게 쪼개 쓰는 **사이클 훔치기** 모드를 상황에 맞게 지원함.

#### 한줄 요약

- 디스크립터 지시서를 통한 비동기 위임, 파편화된 메모리도 묶어버리는 분산 수집, 그리고 프로세서와 다투지 않는 스마트한 버스 점유가 3대 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **직접 메모리 접근 제어기(DMA Controller)**: 출발 및 도착 주소 레지스터, 카운터, 버스 획득 제어 회로를 칩 내부에 탑재하여 거대한 트랜잭션을 독자 구동하는 전용 반도체이다.
- **입출력 메모리 관리 장치(IOMMU)**: 하드웨어 장치가 접근할 때 장치 전용 가상 주소를 메인 물리 주소로 자동 변환해주고, 허락되지 않은 구역 접근은 쳐내는 문지기 반도체 유닛이다.
- **고정 메모리 버퍼(Pinned Memory Buffer)**: 장치와 메모리가 데이터를 주고받는 도중에 운영체제가 해당 공간을 디스크로 빼앗아가지(Swap-out) 못하도록 락을 걸어 상주시켜 둔 안전한 버퍼 구역이다.

</details>

```text
[ 보호 장치가 결합된 직접 메모리 접근 하드웨어 아키텍처 ]
+-------------------------------------------------------------+
| 중앙처리장치 코어 (디스크립터 지시서 작성 및 제어기 기동)   |
+-------------------------------------------------------------+
                              │
[ 시스템 버스 (버스 점유 승인 및 권한 획득 중재 라인) ]
                              │
+-------------------------------------------------------------+
| 전용 직접 메모리 접근 제어기 (버스 마스터)                  |
|  ├─ 주소 레지스터 및 바이트 카운터                          |
|  └─ 흩어진 디스크립터 사슬을 순회하는 분산 수집 엔진        |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 입출력 메모리 관리 장치 (가상 물리 주소 변환 및 접근 검사)  |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 메인 메모리 (상주 락이 걸린 운영체제 커널 버퍼 구역)        |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **직접 메모리 접근 제어기** | 버스 마스터 권한 획득 및 목적지까지의 방대한 데이터 블록 직접 전송 통제 |
| **입출력 메모리 관리 장치** | 가상 주소 물리 변환 제공 및 악의적이거나 잘못된 하드웨어 메모리 접근 철벽 방어 검사 |
| 분산 수집 엔진 | 체인으로 엮여 흩어진 디스크립터 버퍼들을 알아서 순회하며 한 번에 연속 전송 수행 |
| **고정 메모리 버퍼** | 전송이 완료될 때까지 운영체제 페이지 아웃 스와핑 원천 방지 및 안전한 소유권 보장 |

#### 한줄 요약

- 제어기가 버스를 쥐고 흔들며 흩어진 조각들을 모으고, 입출력 관리 장치가 그 주소와 권한을 깐깐하게 감시하여, 고정된 메모리 안으로 안전하게 쏟아붓는 유기적 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 상주(Page Pinning)**: 복사 대상 커널 메모리 페이지가 스왑 아웃되어 디스크로 날아가지 못하게 물리 메모리 공간에 자물쇠를 걸어 강제 상주시키는 필수 사전 징발 작업이다.
- **완료 통지(Completion Notification)**: 제어기가 지시받은 카운터 바이트 수를 100% 인출하여 임무를 완수한 직후, 중앙처리장치로 인터럽트 신호를 날려 끝났음을 보고하는 통보 절차이다.

</details>

```text
[ 호스트 장치 드라이버의 전송 설정 및 가동 흐름 ]
                     │
                     ▼
  [ 1. 메모리 물리적 고정 및 관리 장치 매핑 묶기 ]
                     │
                     ▼
  [ 2. 디스크립터 지시서 작성 및 제어기 기동 킥오프 ]
                     │
                     ▼
  [ 3. 제어기의 버스 마스터 획득 및 데이터 쏟아붓기 ]
                     │
                     ▼
  [ 4. 장치의 완료 통지 발송 및 잔여 버퍼 소유권 정리 ]
```

### 동작 원리

1. 버퍼 매핑: **페이지 상주**를 통해 메모리가 도망가지 못하게 보장하고 관리 장치에 가상 주소를 매핑함.
2. 제어기 기동: 커널이 **전송 디스크립터** 지시서를 메모리에 게시하고 장치에게 시작 킥오프 신호를 줌.
3. 버스 획득 및 전송: 하드웨어가 버스 마스터 권한을 쥐고 장치와 메모리 간 방대한 블록 데이터를 직접 왕복 전송함.
4. 완료 통지 및 정리: 임무가 끝나면 인터럽트 **완료 통지**를 발송하고 걸어두었던 매핑과 버퍼 소유권을 원상 복구 해제함.

#### 한줄 요약

- 도망가지 않게 메모리를 묶고(Pinning), 지시서를 주어 기동시킨 뒤(Kickoff), 묵묵히 버스를 타고 짐을 나르게 한 후(Direct Transfer), 다 끝나면 알람을 받고(Interrupt) 정리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **프로그램 입출력(Programmed I/O)**: 전용 제어기 없이 코어가 바보같이 입출력 기계어 루프를 뺑뺑이 돌며 바이트 데이터를 직접 하나하나 읽고 옮기는 극비효율적 구형 방식이다.
- **버스트 모드(Burst Mode)**: 제어기가 버스 제어권을 한 번 움켜쥐면 맡겨진 블록 데이터 짐 나르기가 완전히 끝날 때까지 버스를 절대 놓지 않고 독점해 버리는 최고속 막가파 방식이다.

</details>

| 비교 항목 | 직접 메모리 접근 방식 | 프로그램 입출력 방식 | 인터럽트 입출력 방식 |
|:---|:---|:---|:---|
| 전송 통제 총괄 주체 | 전용 **직접 메모리 접근 제어기** | 중앙처리장치 코어 | 중앙처리장치 코어 |
| 코어의 막노동 관여 수준 | 설정 및 완료 알람 예외만 가볍게 처리 | 코어가 데이터 이동 반복문 루프를 직접 수행 | 인터럽트 서비스 루틴 안에서 직접 쪼개서 복사 |
| 적합한 타깃 전송 크기 | 고속 스토리지와 네트워크 등 대용량 데이터 블록 전송 | 키보드, 마우스 등 초소형 단발 입력 데이터 전송 | 타이머, 직렬 통신 등 중소형 불규칙 데이터 전송 |
| 시스템 버스 제어 권한 | **버스 마스터**로 직접 점유 제어 주도권 행사 | 버스 슬레이브로 철저히 피동적 제어당함 | 버스 슬레이브로 철저히 피동적 제어당함 |
| 기본 전송 덩어리 단위 | 4킬로바이트 이상의 묵직한 대형 페이지 섹터 | 바이트 또는 단어(Word) 단위 쪼가리 전송 | 바이트 또는 단어(Word) 단위 쪼가리 전송 |

#### 한줄 요약

- 과거에는 코어가 일일이 짐을 져 날랐지만(PIO, Interrupt I/O), 이제는 무거운 짐은 무조건 전용 하드웨어 제어기(DMA)가 트럭을 몰고 나르는 구조로 완전히 진화했다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 일관성(Cache Coherency)**: 제어기가 몰래 메인 메모리를 덮어썼는데 코어 캐시에는 옛날 데이터가 남아있을 경우 엇박자가 나는 현상으로, 전송 전후로 캐시를 비우거나 날려버리는 동기화 처리가 필수적이다.
- **버퍼 소유권(Buffer Ownership)**: 전송이 한창 진행 중일 때 코어와 하드웨어 제어기가 동일한 메모리 버퍼 구역을 동시에 건드려 엉망이 되지 않도록 락을 통해 소유권을 명확히 배타적으로 분리 통제하는 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제어기가 몰래 메모리를 갱신했으나 코어 캐시에 구버전 데이터가 잔존하여 치명적 파손 초래 | 제어기 읽기 전 캐시 비우기 및 쓰기 후 즉각 무효화 통제를 통한 **캐시 일관성** 강제 보장 | 프로세서와 장치 간 어긋남 없는 완벽한 데이터 정합성 유지 및 오류 없는 전송 100% 수행 |
| 전송이 한창 진행되는 도중 운영체제의 뜬금없는 요구 페이징 스왑 발동으로 물리 주소 이탈 | 커널 메모리 할당 레벨에서 물리 **페이지 상주** 고정 잠금을 예외 없이 강제 적용 | 허공에 데이터를 쏟아붓는 전송 중 데이터 파손 원천 방지 및 시스템 안전성 절대 확보 |
| 고장 나거나 해킹당한 확장 카드의 악의적 펌웨어가 커널 메모리를 불법으로 무단 침범 파괴 | 보호 장치(IOMMU) 기반 주소 영역 엄격 격리 및 접근 권한 하드웨어 필터링 차단 방어막 가동 | 악의적이거나 버그 덩어리인 하드웨어 침범 방어 및 커널 메모리 공간 절대 보안 유지 |
| 짐 나르는 제어기가 버스를 장시간 독점하여 프로세서 메인 연산을 위한 메모리 인출 정지 파동 | 찰나를 쪼개 쓰는 **사이클 훔치기** 도입 및 버스 점유 최대 할당량 타임아웃 제어 튜닝 | 중앙처리장치 파이프라인 정지 현상 억제 예방 및 시스템 전체 버스 대역폭의 공정 분배 |

#### 한줄 요약

- 캐시를 밀어버려 일관성을 맞추고, 도망가지 못하게 물리 락을 채우며, 문지기(IOMMU)를 세워 보안을 틀어막고, 쪼개어 버스를 점유하게 하여 코어 연산 방해를 최소화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **제어 최적화 결정 기준(Optimization Criteria)**: 대상 입출력 시스템의 한 방 전송 블록 크기, 요구되는 보안 격리 정책, 장착된 중앙처리장치의 캐시 구조를 종합 평가하여 동작 모드 및 캐시 동기화 파라미터를 확정하는 프레임워크이다.

</details>

- 방대한 대용량 고속 블록 전송은 보호 장치가 결합된 **직접 메모리 접근 방식**, 단발적인 센서나 쪼가리 전송은 **프로그램 입출력**을 선택함

#### 한줄 요약

- 나를 짐의 크기와 보안 수준, 그리고 캐시 어긋남의 대가를 치밀하게 계산하여 코어가 짐을 짊어질지, 아니면 하드웨어 트럭 기사를 고용할지 결정해야 한다.
