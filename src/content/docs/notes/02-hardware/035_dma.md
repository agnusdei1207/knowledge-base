## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU의 직접적인 개입 없이 전용 DMA 제어기(DMAC)가 버스 마스터(Bus Master) 권한을 획득하여 주기억장치(DRAM)와 고속 주변장치 간에 블록 데이터를 고속으로 직접 전송하는 하드웨어 기술.
- **복사 오버헤드(Copy Overhead)**: CPU 코어가 레지스터를 통해 데이터를 한 워드씩 루프로 복사할 때 연산 파이프라인과 버스가 낭비되는 성능 저하 현상.
- **버스 마스터(Bus Master)**: CPU 대신 시스템 주소/데이터 버스의 제어권을 획득하여 읽기·쓰기 트랜잭션을 독자적으로 주도할 수 있는 장치.

</details>

- 정의/개념: 전용 DMA 제어기(DMAC)가 버스 마스터 권한을 획득하여 CPU 개입 없이 주기억장치와 고속 주변 장치 간 블록 데이터를 직접 전송하는 **하드웨어 전송 아키텍처**
- 배경/필요성: CPU의 소프트웨어 워드 단위 루프 복사에 따른 연산 자원 낭비(CPU Overburden) 제거 및 대용량 I/O 버스 전송 효율 극대화

#### 한줄 요약
- DMA는 CPU 대신 전용 제어기가 버스를 주도하여 메모리와 장치 간 대용량 데이터를 직접 전송함으로써 CPU 연산력을 보존한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사이클 스틸링(Cycle Stealing)**: DMA 제어기가 CPU의 메모리 비접근 유휴 사이클을 1워드 단위로 가로채어 전송함으로써 CPU 연산 중단을 최소화하는 모드.
- **버스트 모드(Burst Mode)**: 버스 제어권을 한 번 선점한 후 데이터 블록 전체를 연속해서 최고속으로 전송하는 모드.
- **산란-집적(Scatter-Gather)**: 물리적으로 흩어진 복수의 불연속 메모리 버퍼들을 연결 리스트(Descriptor)로 묶어 단 1회의 DMA 명령으로 연속 전송하는 기법.

</details>

- 전송 시작 설정과 완료 인터럽트 수신 시에만 개입하여 **CPU 연산 파이프라인의 100% 가동률** 보장
- **버스 요청(BR)과 버스 승인(BG)** 핸드셰이크를 통해 시스템 버스 제어권을 안전하게 위임 및 회수
- 물리적으로 불연속한 메모리 페이지들을 단일 트랜잭션으로 일괄 전송하는 **산란-집적(Scatter-Gather) DMA** 지원

#### 한줄 요약
- 버스 마스터링으로 CPU 부하를 제거하고, 사이클 스틸링/버스트 모드로 전송 효율을 조율하며, 산란-집적으로 비연속 버퍼를 고속 전송한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주소 레지스터(Address Register)**: 전송할 메모리의 물리 시작 주소를 보관하고 전송 시마다 주소 크기만큼 자동 증가/감소하는 레지스터.
- **카운트 레지스터(Count Register)**: 전송할 총 바이트(또는 워드) 수를 보관하고 전송마다 1씩 감소하여 0 도달 시 완료 인터럽트를 발생하는 레지스터.
- **버스 요청/승인 신호(BR / BG)**: DMAC가 CPU에 버스 권한을 요청(BR)하고 CPU가 버스를 양보(BG)하는 하드웨어 제어 신호.

</details>

```text
[DMA 데이터 전송 체계]
  │
  ├─ [호스트 프로세서] (Host CPU Core, MMIO 초기화 및 IRQ 처리)
  │
  ├─ [DMA 제어기] (DMAC, 독립적 버스 마스터)
  │     ├─ [주소/카운트 레지스터] (MAR, TCR 자동 증감 계수)
  │     ├─ [제어/상태 레지스터] (CSR, 동작 모드 및 전송 완료)
  │     ├─ [산란-집적 엔진] (Scatter-Gather 디스크립터 체인)
  │     └─ [버스 중재 로직] (BR/BG 제어선 핸드셰이크)
  │
  ├─ [시스템 상호연결 및 IOMMU] (주소 변환 및 디바이스 격리)
  │
  ├─ [주기억장치] (DRAM Memory, DMA 송수신 버퍼)
  │
  └─ [고속 주변 장치] (NVMe SSD, 100GbE NIC, 내부 FIFO)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 주소 레지스터 (MAR) | 전송할 메모리의 시작 물리 주소를 보관하고 **전송 시마다 주소 자동 증감** |
| 카운트 레지스터 (TCR) | 전송 잔여 바이트 수를 계수하고 **0 도달 시 완료 인터럽트 발행** |
| 산란-집적 엔진 | 비연속 물리 메모리 디스크립터 체인을 순회하며 **연속 DMA 일괄 수행** |
| IOMMU / SMMU | 장치 DMA 요청 주소를 가상에서 물리 주소로 변환하고 **비인가 접근 격리** |

#### 한줄 요약
- 주소·카운트 레지스터가 CPU의 워드 단위 반복 전송을 대신 떠맡고 산란-집적 엔진이 연속 버퍼를 확보해야 하던 부담까지 없애는 대신, 장치가 물리 메모리에 직접 닿게 되므로 IOMMU가 그 접근을 주소 공간 격리로 되막는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **입출력 메모리 관리 유닛(Input-Output Memory Management Unit, IOMMU)**: 주변 장치의 DMA 요청 주소를 가상 주소에서 물리 주소로 변환하고 비인가 메모리 접근을 차단하는 보안 하드웨어.

</details>

```text
[CPU의 DMAC 레지스터 설정 (주소·바이트수·방향)]
       │
       ▼
 1. DMAC의 CPU 대상 버스 요청(BR) 신호
       │
       ▼
 2. CPU 버스 승인(BG) 및 하이임피던스 전환
       │
       ▼
 3. 전송 모드 분기 판정
   ├─ [버스트 모드] ──> 버스 연속 독점 점유, 전체 블록 일괄 전송
   └─ [사이클 스틸링] ──> 1워드 전송 후 버스 반환, CPU와 교대 공유
       │
       ▼
 4. 카운터 0 도달 시 버스 제어권 반납 및 완료 IRQ 발행
       │
       ▼
 5. CPU 완료 인터럽트 수신 및 후속 연산 진행
```

분기 결과: **버스트 모드**는 버스를 연속 점유하여 전송 대역폭을 높이나 CPU 메모리 접근이 일시 정지되며, **사이클 스틸링**은 워드마다 버스를 양보하여 CPU 연산 중단을 방지함

**동작 원리**

1. **버스 제어권 요청(BR)**: 주변 장치의 DREQ를 수신한 DMAC가 CPU에 버스 요청(Bus Request) 신호를 하드웨어 핀으로 전송
2. **CPU 버스 승인(BG)**: CPU가 현재 버스 사이클을 마친 즉시 버스 승인(Bus Grant)을 반환하고 주소/데이터 핀을 하이임피던스(High-Z) 상태로 전환
3. **전송 모드 분기 판정**: 설정된 전송 정책에 따라 버스를 독점하는 버스트 모드 또는 1워드 단위로 버스를 반환하는 사이클 스틸링 모드 수행
4. **버스 제어권 반납 및 IRQ 발행**: 전송마다 카운트 레지스터가 차감되어 0에 도달하면 버스 점유를 해제하고 CPU로 버스 제어권 반납 및 완료 IRQ 발행
5. **완료 인터럽트 수신**: CPU가 DMAC의 IRQ를 수신하여 전송 성공을 확인하고 대기 중이던 후속 프로세스 연산 재개

#### 한줄 요약
- 전송 한 건마다 버스 획득과 반환, 완료 통지가 고정 비용으로 따라붙으므로 전송 길이가 짧을수록 이 준비 구간의 비중이 커지고, 그만큼 CPU를 덜어 준다는 이득도 함께 줄어든다.

## Ⅴ. 종류 및 비교

| DMA 전송 모드 | 버스트 모드 (Burst Mode) | 사이클 스틸링 (Cycle Stealing) | 디맨드 모드 (Demand Mode) |
|:---|:---|:---|:---|
| 적용 기준 | NVMe SSD, 고속 GPU 등 초고속 대용량 블록 전송 시 | CPU 실시간 연산 반응성 유지가 필수적인 임베디드 환경 | 데이터 생성 및 수신 주기가 가변적인 저속 주변 장비 연결 시 |
| 핵심 특징 | 버스 제어권을 1회 선점한 후 **블록 전체 전송 완료 시까지 연속 독점** | 1워드 전송마다 버스를 즉시 반환하며 **CPU와 버스 유휴 사이클 공유** | 장치의 DREQ 요청 신호가 **활성 상태를 유지하는 동안에만 버스 점유** |
| 한계 | 전송 완료 시까지 **CPU의 외부 메모리 버스 접근 일시 동결** | 워드 단위 잦은 버스 중재 핸드셰이크로 인한 **총 전송 시간 증가** | 장치 데이터 준비 지연 시 버스 활용 효율이 급감하는 **장치 종속성** |

#### 한줄 요약
- 최고 속도의 대용량 전송에는 버스트 모드가 적합하고, CPU 응답성을 유지해야 하는 환경에는 사이클 스틸링이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 정리 및 무효화(Cache Clean & Invalidate)**: DMA 읽기 전 더티 캐시를 메모리에 반영(Clean)하고, DMA 쓰기 후 CPU의 구 캐시 라인을 무효화(Invalidate)하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DMA 전송 데이터와 CPU 캐시 간 불일치 | 디바이스 드라이버 레벨 **캐시 무효화 및 플러시** | 물리 메모리와 캐시 간 데이터 일관성 보장 |
| 가상 메모리 페이징에 따른 물리 불연속 버퍼 분산 | **산란-집적(Scatter-Gather)** 디스크립터 엔진 | 메모리 복사 없는 제로카피 일괄 전송 |
| 악의적 장치의 DMA를 통한 커널 메모리 침범 | 하드웨어 **IOMMU/SMMU 주소 격리** 적용 | 장치별 DMA 접근 영역 제한 및 메모리 보호 |

#### 한줄 요약
- 실무에서는 캐시 플러시/무효화로 일관성을 유지하고, 산란-집적으로 비연속 페이지를 처리하며, IOMMU로 DMA 보안을 격리한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **디스크립터 링(Descriptor Ring)**: 호스트 드라이버와 DMAC 간에 송수신 메모리 디스크립터를 원형 큐 형태로 공유하여 연속적인 제로카피 블록 전송을 지원하는 데이터 구조.
- **바운스 버퍼(Bounce Buffer)**: 구형 32비트 DMA 장치가 64비트 상위 메모리 영역에 직접 접근할 수 없을 때, 저위 메모리 공간에 임시 할당하여 데이터를 중계 복사하는 커널 완충 버퍼.
- **원격 직접 메모리 접근(Remote Direct Memory Access, RDMA)**: OS 커널 및 CPU 개입 없이 고속 네트워크 패브릭을 통해 원격 노드의 메모리에 직접 읽기·쓰기를 수행하는 초저지연 통신 기술.

</details>

- 로컬 버스 중심의 DMA 전송 체계는 클라우드 가상화 및 AI 클러스터 환경에서 가상 머신 간 직접 전송을 보장하는 IOMMU 기반 장치 패스스루와 노드 간 경계를 허무는 **원격 직접 메모리 접근(RDMA)** 패브릭으로 확장 진화 추세
- 고속 I/O 디바이스 드라이버 설계 시에는 32비트 주소 제한에 따른 **바운스 버퍼(Bounce Buffer)** 중계 복사 오버헤드를 원천 차단하고, **디스크립터 링(Descriptor Ring)** 기반의 산란-집적 엔진과 캐시 무효화 타이밍을 정밀 제어하는 공학적 통찰 필요

#### 한줄 요약
- DMA는 RDMA 및 IOMMU 가상화로 확장 진화하고 있으며, 실무에서는 바운스 버퍼 병목 제거와 디스크립터 링 기반 캐시 정합성 제어가 핵심 통찰이다.
