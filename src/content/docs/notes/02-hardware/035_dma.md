## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 DMA 제어기(DMAC)가 버스 마스터 권한을 획득하여 주변장치와 메인 메모리 간에 대용량 데이터를 직접 전송하는 기술.
- **복사 오버헤드(Copy Overhead)**: CPU 코어가 직접 레지스터를 통해 데이터를 한 바이트씩 복사하면서 발생하는 연산력 낭비.
- **버스 마스터(Bus Master)**: CPU 대신 시스템 버스의 제어권을 획득하여 읽기/쓰기 트랜잭션을 주도할 수 있는 권한을 가진 장치.

</details>

- 정의/개념: CPU 개입 없이 전용 DMA 제어기(DMAC)가 버스 마스터 권한을 획득하여 주변장치와 메인 메모리 간에 대용량 블록 데이터를 직접 고속 전송하는 기술
- 배경/필요성: CPU가 바이트/워드 단위로 직접 메모리 복사를 수행할 때 발생하는 **CPU 연산력 낭비(Copy Overhead) 및 메모리 버스 병목 해소**

#### 한줄 요약

- CPU 개입 없이 전용 제어기가 **메모리와 주변장치 간 블록 직접 전송** 수행

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **전송 디스크립터(Transfer Descriptor)**: 출발지/목적지 주소, 전송 길이, 제어 플래그를 담은 메모리 상의 작업 명세서 구조체.
- **Scatter-Gather DMA**: 물리 메모리에 파편화되어 흩어져 있는 다수의 버퍼들을 하나의 디스크립터 체인으로 연결하여 한 번에 연속 전송하는 기법.
- **사이클 훔치기(Cycle Stealing)**: CPU가 시스템 버스를 사용하지 않는 유휴 클록 사이클마다 DMA가 버스를 잠시 점유하여 1워드씩 전송하는 모드.

</details>

- CPU는 **전송 디스크립터** 설정 및 완료 인터럽트만 처리하고 실제 데이터 전송은 DMAC가 전담
- 물리 메모리 단편화를 극복하기 위해 비연속 버퍼들을 체인으로 묶어 일괄 전송하는 **분산 수집(Scatter-Gather)** 지원
- 시스템 버스 점유 전략에 따라 **버스트 모드(Burst)**, **사이클 훔치기(Cycle Stealing)**, **블록 전송 모드** 선택 지원

#### 한줄 요약

- **전송 디스크립터·Scatter-Gather·사이클 훔치기(Cycle Stealing)**를 통한 CPU 부하 최소화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IOMMU(Input-Output Memory Management Unit)**: DMA 장치가 메모리에 접근할 때 가상 주소를 물리 주소로 변환하고 접근 권한을 검사하는 하드웨어.
- **Pinned Buffer(고정 메모리 버퍼)**: DMA 전송 중 OS가 해당 물리 메모리 페이지를 스왑 아웃하거나 이동시키지 못하도록 락을 건 버퍼.

</details>

```text
[ 보호 장치가 결합된 DMA 하드웨어 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 중앙처리장치 (CPU Core : 디스크립터 작성 및 DMAC 킥오프)    │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 시스템 버스 (Bus Request / Grant) ]
┌──────────────────────────────┴──────────────────────────────┐
│ 전용 DMA 컨트롤러 (DMAC : Bus Master Engine)                │
│  ├─ 소스/목적지 주소 레지스터 및 전송 카운터                │
│  └─ 흩어진 버퍼를 순회하는 Scatter-Gather Engine            │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ IOMMU (장치 가상 주소 ──> 물리 주소 변환 및 메모리 접근 보호)│
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 메인 메모리 (DRAM : Page Pinning 고정된 DMA 커널 버퍼)      │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: CPU, 시스템 버스, DMA 제어기, IOMMU 및 메인 메모리(Pinned Buffer) 간의 DMA 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 직접 메모리 접근 제어기 | 버스 마스터 권한 획득 및 목적지까지의 방대한 데이터 블록 직접 전송 통제 |
| 입출력 메모리 관리 장치 | 가상 주소 물리 변환 제공 및 악의적이거나 잘못된 하드웨어 메모리 접근 철벽 방어 검사 |
| 분산 수집 엔진 | 체인으로 엮여 흩어진 디스크립터 버퍼들을 알아서 순회하며 한 번에 연속 전송 수행 |
| 고정 메모리 버퍼 | 전송이 완료될 때까지 운영체제 페이지 아웃 스와핑 원천 방지 및 안전한 소유권 보장 |

#### 한줄 요약

- **DMA 컨트롤러·IOMMU(주소 변환/보호)·Scatter-Gather 엔진·Pinned 메모리** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Page Pinning**: DMA 전송 대상 메모리 페이지가 스왑 영역으로 쫓겨나지 않도록 물리 프레임에 잠금(Lock)을 설정하는 절차.

</details>

```text
[ 디바이스 드라이버 DMA 전송 요청 ]
                 │
                 ▼
 [ 1. 대상 메모리 Page Pinning 및 IOMMU 매핑 ]
                 │
                 ▼
 [ 2. Scatter-Gather 디스크립터 체인 구성 ]
                 │
                 ▼
 [ 3. DMAC 시작 레지스터 설정 (Kick-off) ]
                 │
                 ▼
 [ 4. DMAC가 버스 마스터 획득 및 직접 전송 ]
                 │
                 ▼
 [ 5. 전송 완료 시 CPU로 완료 인터럽트 발생 ]
                 │
                 ▼
 [ 6. 드라이버가 IOMMU 언매핑 및 Page Unpinning ]
```

**동작 원리**

1. **메모리 고정**: 드라이버가 사용자/커널 버퍼를 Page Pinning하고 IOMMU에 DMA 가상 주소 매핑
2. **디스크립터 작성**: 출발지, 목적지, 길이 정보를 담은 디스크립터 링을 메모리에 구성
3. **DMAC 기동**: 드라이버가 DMAC 레지스터에 디스크립터 시작 주소를 쓰고 전송 시작 명령 전달
4. **직접 전송**: DMAC가 버스 중재기로부터 버스 마스터를 획득하여 장치 $\leftrightarrow$ 메모리 간 블록 데이터 직접 복사
5. **완료 통보**: 전송 카운터가 0이 되면 CPU로 완료 인터럽트를 발생시키고 매핑 해제

#### 한줄 요약

- Page Pinning $\to$ **디스크립터 작성 $\to$ 버스 마스터 획득 및 직접 전송 $\to$ 완료 인터럽트**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **DMA vs PIO vs Interrupt-driven I/O**:
  - DMA: DMAC가 블록 직접 전송, CPU 개입 최소화 (고속 대용량)
  - PIO: CPU가 루프를 돌며 바이트 단위 복사 (초저속 단순 장치)
  - Interrupt I/O: 바이트 단위 완료 시마다 ISR 호출 (중속 소량 장치)

</details>

| 비교 항목 | 직접 메모리 접근 (DMA) | 프로그램 입출력 (PIO) | 인터럽트 기반 I/O |
|:---|:---|:---|:---|
| 전송 제어 주체 | 전용 DMA 컨트롤러 (Bus Master) | CPU 코어 (바쁜 대기 루프) | CPU 코어 (ISR 문맥 교환) |
| 전송 단위 및 성능 | 블록 / 페이지 단위 대용량 초고속 전송 | 바이트 / 워드 단위 소량 전송 (극저속) | 바이트 / 워드 단위 소량 전송 (중속) |
| 한계 및 위험 | 캐시 일관성(Coherency) 불일치 및 IOMMU 보호 필요 | CPU 100% 점유로 다른 작업 불가 | 고속 I/O 시 인터럽트 폭풍(Storm) 발생 |

#### 한줄 요약

- 대용량 블록은 **DMA**, 단순 센서/단발 입력은 **PIO/인터럽트**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DMA 캐시 코히런시(Cache Coherency)**: DMA가 메모리를 갱신했을 때 CPU 캐시의 옛날 데이터가 남거나, CPU 캐시의 더티 데이터가 메모리에 반영되지 않아 발생하는 불일치.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제어기가 몰래 메모리를 갱신했으나 코어 캐시에 구버전 데이터가 잔존하여 치명적 파손 초래 | 제어기 읽기 전 캐시 비우기 및 쓰기 후 즉각 무효화 통제를 통한 **캐시 일관성** 강제 보장 | 프로세서와 장치 간 어긋남 없는 완벽한 데이터 정합성 유지 및 오류 없는 전송 100% 수행 |
| 전송이 한창 진행되는 도중 운영체제의 뜬금없는 요구 페이징 스왑 발동으로 물리 주소 이탈 | 커널 메모리 할당 레벨에서 물리 **페이지 상주** 고정 잠금을 예외 없이 강제 적용 | 허공에 데이터를 쏟아붓는 전송 중 데이터 파손 원천 방지 및 시스템 안전성 절대 확보 |
| 고장 나거나 해킹당한 확장 카드의 악의적 펌웨어가 커널 메모리를 불법으로 무단 침범 파괴 | 보호 장치(IOMMU) 기반 주소 영역 엄격 격리 및 접근 권한 하드웨어 필터링 차단 방어막 가동 | 악의적이거나 버그 덩어리인 하드웨어 침범 방어 및 커널 메모리 공간 절대 보안 유지 |
| 짐 나르는 제어기가 버스를 장시간 독점하여 프로세서 메인 연산을 위한 메모리 인출 정지 파동 | 찰나를 쪼개 쓰는 **사이클 훔치기** 도입 및 버스 점유 최대 할당량 타임아웃 제어 튜닝 | 중앙처리장치 파이프라인 정지 현상 억제 예방 및 시스템 전체 버스 대역폭의 공정 분배 |

#### 한줄 요약

- **DMA 캐시 플러시/무효화·Page Pinning·IOMMU 격리·Cycle Stealing/Burst 조율**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **RDMA(Remote DMA)**: 네트워크를 통해 원격 노드의 메모리에 OS 커널 및 CPU 개입 없이 직접 읽고 쓰는 초저지연 네트워킹 기술 (InfiniBand, RoCEv2).

</details>

- 엔터프라이즈 스토리지 및 네트워크 환경에서 **Scatter-Gather DMA 및 IOMMU 기반 하드웨어 메모리 격리 표준 채택**

#### 한줄 요약

- **블록 크기, 캐시 일관성, 메모리 보호(IOMMU)**를 고려한 최적 DMA 전송 구현
