## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 제어기가 메인 메모리와 주변장치 사이의 데이터 전송을 주도하는 기술.
- **복사 오버헤드(Copy Overhead)**: CPU 코어가 직접 레지스터를 통해 데이터를 한 바이트씩 복사하면서 발생하는 연산력 낭비.
- **버스 마스터(Bus Master)**: CPU 대신 시스템 버스의 제어권을 획득하여 읽기·쓰기 트랜잭션을 주도할 수 있는 권한을 가진 장치.

</details>

- 정의/개념: 전용 제어기가 **버스 마스터**로 올라서 주기억장치와 입출력 장치 사이를 직접 잇는 **직접 메모리 접근(DMA)**
- 배경/필요성: CPU 프로그램 I/O 직접 복사 방식으로는 **데이터 전송량 증가에 따른 CPU 연산 병목 극복 불가**

#### 한줄 요약
- DMA가 옮기는 것은 데이터가 아니라 버스 소유권이며, CPU가 잠시 주인 자리를 내주는 구조라는 점에서 이후의 모든 부작용이 파생된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사이클 스틸링(Cycle Stealing)**: DMA가 CPU의 버스 유휴 사이클을 가로채 1워드씩 전송하는 모드.
- **버스트 모드(Burst Mode)**: 버스를 한 번 선점한 후 전체 블록을 연속해서 고속 전송하는 모드.
- **산란-집적(Scatter-Gather)**: 물리적으로 불연속한 여러 메모리 버퍼를 한 번의 DMA 명령으로 연속 전송하는 기법.

</details>

- 데이터 복사 루프를 제거하고 설정과 완료 처리만 CPU에 남김
- **버스 마스터** 권한을 획득해 독자적으로 읽기·쓰기 트랜잭션 주도
- 전송 완료 시에만 인터럽트를 발생시켜 CPU 개입 최소화

#### 한줄 요약
- 설정 비용이 전송량과 무관하게 고정이므로 작은 전송에서는 DMA가 오히려 손해이며, 손익분기 전송 크기가 존재한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주소 레지스터(Address Register)**: 전송할 메모리의 시작 물리 주소를 보관하고 전송마다 자동 증가하는 레지스터.
- **카운트 레지스터(Count Register)**: 전송할 총 바이트(또는 워드) 수를 저장하고 전송 시마다 감소하는 레지스터.
- **버스 요청(Bus Request, BR)**: DMA 제어기가 CPU에 버스 사용 권한을 넘겨달라고 요청하는 제어 신호.
- **버스 승인(Bus Grant, BG)**: CPU가 현재 버스 사이클을 비우고 DMA에 버스 제어권을 위임하는 응답 신호.

</details>

```text
[DMA 전송 구조]
├─ 호스트 CPU (BR·BG 신호로 버스 소유권 교환)
├─ DMA 컨트롤러
│  ├─ 주소 레지스터 (전송 시작 주소·자동 증가)
│  ├─ 카운트 레지스터 (잔여 전송량·0에서 완료)
│  ├─ 제어·상태 레지스터 (방향·모드·플래그)
│  └─ 버스 중재 회로
├─ 주기억장치
└─ 고속 주변장치 (NVMe·NIC 등)
```

선의 의미: 가지(`├─`)는 소유 관계이며, DMA 전송 중에는 주기억장치와 주변장치가 CPU를 거치지 않고 직접 이어짐

| 구성요소 | 책임 |
|:---|:---|
| **주소 레지스터** | 전송 시작 주소 보관과 전송마다 자동 증가 |
| **카운트 레지스터** | 잔여 전송량 관리와 0 도달 시 완료 통지 |
| 제어/상태 레지스터 | 전송 방향(읽기/쓰기), 전송 모드 설정 및 상태 플래그 보관 |
| 버스 중재 회로 | **버스 요청(BR)** 발행과 **버스 승인(BG)** 수신 |

#### 한줄 요약
- 주소 레지스터가 물리 주소를 다룬다는 점이 DMA의 보안 취약성의 뿌리이며, IOMMU가 등장하기 전까지 장치는 메모리 전체를 볼 수 있었다.

## Ⅳ. 흐름도

```text
CPU가 시작 주소·카운트·방향 설정
        │
   DMA가 BR 인가 → CPU가 BG 응답
        │
   어떤 점유 모드인가?
   ┌────┼──────────┐
버스트     사이클 스틸링   디맨드
 │          │            │
블록 전부를  1워드 전송 후  장치 요청 신호가
연속 전송    즉시 반환      살아 있는 동안 전송
 │          │            │
 │     카운트 0인가?      │
 │      ┌──┴──┐          │
 │    아니오   예         │
 │      │      │         │
 │   재요청   완료        │
 └────┬──┴──────┴─────────┘
      │
  버스 반환 후 완료 인터럽트
```

분기 결과: 세 모드는 같은 전송량을 버스 점유 시간의 길이와 횟수로 다르게 쪼개므로, 총 전송 시간은 비슷해도 CPU가 겪는 최대 대기 시간은 크게 갈림

#### 한줄 요약
- 모드 선택은 처리량과 CPU 응답성 중 무엇을 보장할지의 문제이며, 실시간 시스템이 **버스트 모드**를 피하는 이유도 최악 대기 시간이 예측 불가능해서다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **버스트 모드(Burst Mode)**: 버스를 한 번 선점하여 블록 데이터 전체를 연속 전송하는 모드.
- **사이클 스틸링(Cycle Stealing)**: CPU 메모리 사이클 사이의 유휴 시간을 가로채 1워드 단위로 전송하는 모드.
- **디맨드 모드(Demand Mode)**: I/O 장치의 데이터 준비 신호가 활성화된 동안 전송을 지속하는 모드.

</details>

| DMA 전송 모드 | 버스트·블록 모드 | 사이클 스틸링 | 디맨드 모드 |
|:---|:---|:---|:---|
| 적용 기준 | 대용량 연속 전송 처리량 우선 | CPU 메모리 접근 지연 제한 | 장치 준비 신호에 맞춘 가변 전송 |
| 핵심 특징 | 버스를 연속 점유해 블록 완료 | 짧은 버스 점유 후 CPU에 반환 | 장치 요청 신호 활성 동안 전송 지속 |
| 한계 | CPU 메모리 접근 장시간 차단 | 잦은 중재·반환 오버헤드 | 장치 지연 중 버스 점유 가능 |

#### 한줄 요약
- 세 모드가 나뉘는 축은 버스를 한 번에 얼마나 오래 잡느냐 하나뿐이며, 나머지 차이는 모두 이 점유 시간에서 파생된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IOMMU(Input-Output Memory Management Unit)**: DMA 장치가 사용하는 가상 주소를 물리 주소로 변환하고 메모리 보호를 수행하는 장치.
- **캐시 정리·무효화(Cache Clean/Invalidate)**: 장치가 메모리를 읽기 전 CPU의 더티 데이터를 반영하고, 장치가 쓴 뒤 CPU의 오래된 사본을 폐기하는 작업.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DMA 전송 데이터와 CPU 캐시 불일치 | 방향별 **캐시 정리·무효화** 또는 하드웨어 일관성 사용 | CPU·장치의 최신 버퍼 관찰 일치 |
| 버스트 모드로 인한 CPU 메모리 기아 | **사이클 스틸링** 혼용 및 최대 점유 시간 제한 | CPU 연산 지연 방지 및 응답성 유지 |
| 물리적으로 흩어진 페이지의 전송 복잡도 | **산란-집적** 체인 리스트 적용 | 연속 메모리 할당 실패 방지 및 전송 자동화 |
| 악의적 장치의 비인가 메모리 접근 | **IOMMU** 기반 주소 변환 및 권한 격리 적용 | 가상화 환경 보호 및 메모리 보안성 강화 |

#### 한줄 요약
- 네 문제 모두 CPU를 경로에서 뺀 대가이며, **IOMMU**는 그렇게 잃은 보호를 다시 사 오는 장치라는 점에서 DMA 비용의 일부다.

## Ⅶ. 결론

- 대용량 연속 전송은 **버스트 모드**, CPU 응답성 우선은 **사이클 스틸링** 선택

#### 한줄 요약
- DMA 도입 판단에서 자주 빠지는 항목은 전송 성능이 아니라 캐시 유지보수와 주소 격리의 소프트웨어 비용이며, 이쪽이 실제 통합 기간을 좌우한다.
