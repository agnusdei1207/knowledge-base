## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **DMA(Direct Memory Access)**: CPU 개입 없이 장치와 메모리 사이 데이터를 직접 전송하는 기법.
- **CPU(Central Processing Unit)**: 프로그램 명령을 해석하고 연산을 실행하는 중앙 처리 장치.
- **I/O(Input/Output)**: 호스트 시스템과 주변 장치 간 데이터 주고받는 입출력 체계.
- **CPU 복사 비용(CPU Copy Overhead)**: CPU가 I/O 데이터를 직접 옮기며 소비하는 시간과 버스 대역폭.

</details>

- 정의/개념: 전용 버스 마스터가 I/O 장치와 주기억장치 사이 데이터를 직접 전송하는 **DMA** 방식
- 배경/필요성: CPU가 대량 I/O 데이터를 직접 복사 시 연산 시간 감소 및 버스 대역폭 낭비 발생

#### 한줄 요약

- CPU가 주소·길이·방향을 설정하면 DMA 엔진이 장치와 메모리 사이의 데이터를 직접 전송하고 완료만 통지한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **버스 마스터(Bus Master)**: 인터커넥트에서 메모리 읽기•쓰기 트랜잭션을 직접 시작하는 제어 주체.
- **전송 디스크립터(Transfer Descriptor)**: DMA 엔진이 사용할 주소•길이•방향을 기록한 명세서.
- **분산 수집(Scatter-Gather)**: 흩어진 메모리 버퍼들을 디스크립터 목록으로 묶어 연속 전송하는 기법.

</details>

- 큰 블록 전송 시 **CPU 복사 비용** 대폭 절감
- DMA 컨트롤러의 **버스 마스터** 자격 기반 직접 전송
- 비연속 버퍼를 한 번의 작업으로 처리하는 **분산 수집** 지원

#### 한줄 요약

- 대용량 또는 비연속 버퍼 전송에서는 DMA 설정 비용보다 CPU 복사 절감 이득이 커진다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **DMA 드라이버(DMA Driver)**: 전송 명세 작성과 엔진 기동•완료•오류를 관리하는 소프트웨어.
- **DMA 컨트롤러(DMA Controller)**: 버스 마스터로 장치와 메모리 간 블록 전송을 제어하는 하드웨어.
- **주기억장치 버퍼(Main Memory Buffer)**: 데이터 및 DMA 디스크립터를 보관하는 메모리 영역.

</details>

```text
                       [CPU•DMA 드라이버]
                                |
[I/O 장치] ----- [DMA 컨트롤러] ----- [주기억장치]
```

선의 의미: DMA 컨트롤러를 중심으로 제어 경계와 장치•메모리 데이터 경계가 결합되는 정적 연결 관계.

| 구성요소 | 책임 |
|:---|:---|
| CPU•DMA 드라이버 | 전송 명세 작성•기동•완료 처리 |
| DMA 컨트롤러 | 장치•메모리 간 블록 직접 전송 |
| I/O 장치 | 데이터 입출력 근원지 및 목적지 역할 |
| 주기억장치 | 데이터 및 전송 디스크립터 보관 |

#### 한줄 요약

- CPU가 전송 명세를 제출하면 DMA 컨트롤러가 장치와 메모리 사이의 블록을 옮긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **버퍼 매핑(Buffer Mapping)**: 메모리 버퍼를 장치 주소 공간에 매핑하고 권한을 설정하는 작업.
- **IOMMU(Input-Output Memory Management Unit)**: 장치 DMA 주소를 변환 및 격리하는 하드웨어.
- **전송 완료 통지(Completion Notification)**: 데이터 전송 완료를 CPU 드라이버에 알리는 인터럽트/큐 상태.

</details>

```text
                       [CPU I/O 요청]
                               |
                  1. IOMMU 버퍼 매핑•권한 설정
                               |
                  2. 전송 디스크립터 등록•시작
                               |
                        [DMA 컨트롤러]
                               |
               +--------------------------------+
               | 반복: 디스크립터 잔여 블록    |
               | 3. 장치 주소 변환•접근 판정  |
               | 4. 장치•메모리 블록 전송     |
               +--------------------------------+
                               |
                        [완료 상태 기록]
                               |
                     5. 완료 통지•버퍼 인계
```

### 동작 원리

1. **버퍼 매핑·권한 설정**: DMA 버퍼를 장치 주소 공간에 연결하고 **IOMMU** 적용 시 접근 범위 제한.
2. **전송 디스크립터 등록·시작**: 출발지·목적지 주소, 길이, 방향 기록 후 DMA 엔진 기동.
3. **장치 주소 변환·접근 판정**: 디스크립터의 장치 주소 변환 및 읽기·쓰기 권한 검증.
4. **장치·메모리 블록 전송**: DMA 엔진이 CPU 개입 없이 지정 블록을 장치와 주기억장치 간 이송.
5. **완료 통지·버퍼 인계**: 완료 상태 기록 후 CPU에 알리고 버퍼 소유권 반환.

#### 한줄 요약

- CPU는 버퍼 권한과 전송 디스크립터를 설정하고, DMA 엔진은 직접 전송을 수행한 뒤 완료 상태와 버퍼 소유권을 반환한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **인터럽트 I/O(Interrupt-Driven I/O)**: 장치 준비 시 인터럽트로 CPU에 알리고 CPU가 전송하는 방식.
- **프로그램 I/O(Programmed I/O, PIO)**: CPU가 장치 상태를 계속 폴링하며 데이터까지 직접 복사하는 방식.
- **설정 비용(Setup Overhead)**: 전송 디스크립터 준비, 매핑, 동기화에 소요되는 고정 시간.

</details>

| I/O 방식 | DMA | 인터럽트 I/O | 프로그램 I/O |
|:---|:---|:---|:---|
| 적용 기준 | 대용량•연속•분산 블록 | 비정기 소량 이벤트 | 매우 짧고 단순한 I/O |
| 핵심 특징 | **DMA** 엔진의 블록 직접 전송 | **인터럽트 I/O** 기반 CPU 전송 | **프로그램 I/O** 기반 폴링 전송 |
| 한계 | 설정•동기화•디스크립터 관리 비용 | 인터럽트 문맥 전환 오버헤드 | 바쁜 대기 및 CPU 복사 비용 |

> 요약: 대량은 DMA, 소량은 인터럽트 I/O 선택.

#### 한줄 요약

- 설정 비용을 상쇄하는 대용량·분산 블록은 DMA가 유리하고, 비정기 소량 전송은 인터럽트 I/O가 단순하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **캐시 clean(Cache Clean)**: CPU 캐시 변경분을 주기억장치에 반영하는 동기화 동작.
- **캐시 invalidate(Cache Invalidate)**: DMA 전송으로 바뀐 메모리의 구형 캐시 사본을 무효화하는 동작.
- **버퍼 소유권(Buffer Ownership)**: 버퍼에 접근 가능한 주체(CPU 또는 장치)를 지정하는 제어 상태.
- **메모리 장벽(Memory Barrier)**: 메모리 접근 명령의 실행 순서를 강제 보장하는 동기화 명령.
- **NVMe(Non-Volatile Memory Express)**: 호스트 메모리와 SSD 간 DMA 전송을 수행하는 고속 저장 인터페이스.
- **멱등 재시도(Idempotent Retry)**: 재시도 수행 시에도 중복 부작용 없이 동일 결과를 보장하는 복구 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 캐시 비일관성 발생으로 CPU·장치 간 데이터 불일치 | **캐시 clean**·**캐시 invalidate**·**메모리 장벽** 적용 | DMA 전후 최신 데이터 일관성 보장 |
| DMA 완료 전 CPU 버퍼 접근으로 데이터 손상 | **버퍼 소유권** 관리 및 완료 동기화 적용 | CPU와 장치 간 접근 충돌 차단 |
| 오염된 디스크립터로 인한 무단 메모리 접근 | **IOMMU** 기반 주소 공간 변환 및 권한 검증 | 장치별 허용 영역 외 메모리 접근 차단 |
| 버스 독점 및 중간 오류에 의한 부분 전송 실패 | 전송 크기 제한 및 **멱등 재시도** 구조 적용 | 버스 대역폭 공정성 및 복구 실패 방지 |

> 사례: **NVMe** 버퍼 접근 보호를 위한 **IOMMU** 격리 적용

#### 한줄 요약

- IOMMU로 장치의 DMA 주소 범위를 제한하고 버퍼 소유권을 완료 시점에 인계해 메모리 침범과 동시 재사용을 방지한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **대용량 블록 전송(Bulk Block Transfer)**: 전송 설정 비용보다 CPU 복사 절감 효과가 큰 데이터 이동.
- **전송 방식 선택 기준(I/O Method Selection Criteria)**: 데이터 크기와 설정 오버헤드를 비교하여 최적 전송 방식을 결정하는 기준.

</details>

- **전송 방식 선택 기준**에 따라 대용량 전송은 **DMA**, 소량 전송은 **인터럽트 I/O** 선택

#### 한줄 요약

- CPU 복사 절감 이득이 버퍼 매핑과 디스크립터 설정 비용보다 클 때 DMA를 사용하고, IOMMU로 접근 범위를 격리한다.
