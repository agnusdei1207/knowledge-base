## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **직접 메모리 접근 (Direct Memory Access, DMA)**: 초고속 주변장치(SSD, NIC, GPU)와 시스템 메인 메모리(DRAM) 간의 대용량 데이터 전송 시 CPU 코어 연산기를 우회하여, 하드웨어 DMA 컨트롤러가 직접 메모리 제어권을 획득해 전송을 대행하는 제어 방식.
- **CPU 복사 비용 (CPU Copy Overhead)**: CPU 코어가 직접 레지스터 읽기/쓰기 바이트 루프를 구동하며 I/O 데이터를 복사하느라 타 연산 스레드를 구동하지 못하는 연산력 낭비 오버헤드.
- **버스 마스터 (Bus Master)**: CPU 대신 시스템 주소/데이터 버스(Bus) 제어권을 획득하여 트랜잭션을 시작 및 통제할 수 있는 권한을 가진 전용 제어 장치.

</details>

- 정의/개념: CPU 개입 없이 전용 하드웨어 제어기(DMAC)가 **버스 마스터(Bus Master)** 권한을 획득하여 주변장치와 메인 메모리 간 블록 데이터를 직접 전송하는 **DMA(Direct Memory Access)** 기술.
- 배경/필요성: 대용량 데이터 입출력 시 CPU 코어가 바이트 단위 복사를 직접 전담하면 막대한 **CPU 복사 비용(CPU Copy Overhead)**이 발생하여 전체 시스템 성능이 정지(Stall)하므로, 입출력 통제를 전용 컨트롤러로 이관하기 위해 등장.

#### 한줄 요약
- CPU 복사 전송 오버헤드를 없애기 위해 DMAC 하드웨어가 버스 제어권을 잡고 메인 메모리와 주변장치 간 블록 입출력을 직접 가동하는 무지연 전송 기술.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **전송 디스크립터 (Transfer Descriptor)**: DMA 컨트롤러가 인출할 출발지 주소(Source), 목적지 주소(Destination), 전송 바이트 크기(Length), Control Flags 정보를 저장하고 있는 메모리 구조체.
- **분산-수집 (Scatter-Gather DMA)**: 메인 메모리 상에 파편화되어 흩어져 있는 복수의 링 버퍼들을 디스크립터 체인(Chain)으로 묶어 단 1회의 DMA 기동으로 연속 전송하는 고급 DMA 기법.
- **사이클 스티어링 (Cycle Stealing)**: CPU가 버스를 사용하지 않는 일시 유휴 사이클 시간에 DMA 컨트롤러가 버스 제어권을 살짝 빌려(Steal) 바이트 데이터를 쪼개어 전송하는 기법.

</details>

- 입출력 시작 시 시작 주소와 카운터를 지정하는 **전송 디스크립터(Transfer Descriptor)** 설정만 CPU가 수행하고 실제 전송 중 CPU 관여율 0% 달성.
- 물리 메모리 파편화 문제를 해결하기 위해 여러 버퍼를 체인으로 연결해 한번에 처리하는 **분산-수집(Scatter-Gather DMA)** 지원.
- 버스 제어권을 잡는 방식에 따라 블록 전체를 전송하는 Burst Mode, CPU 사이클을 쪼개 쓰는 **사이클 스티어링(Cycle Stealing)** 모드로 분류.

#### 한줄 요약
- Descriptor 기반 비동기 블록 전송, Scatter-Gather 분산 버퍼 처리 및 Cycle Stealing/Burst Mode 버스 점유 제어를 특성으로 가짐.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **DMA 제어기 (DMA Controller, DMAC)**: 주소 레지스터, 카운터 레지스터, 버스 제어 회로를 탑재하여 DMA 트랜잭션을 구동하는 전용 반도체.
- **IOMMU (Input-Output Memory Management Unit)**: DMA 장치가 메모리 접근 시 장치 전용 가상 주소(IOVA)를 메인 메모리 물리 주소(PA)로 변환하고 접근 보호 권한을 검사하는 하드웨어 유닛.
- **주기억장치 버퍼 (Main Memory Buffer / Ring Buffer)**: CPU와 DMA 장치가 데이터를 공유 주고받기 위해 락업 매핑해 둔 DRAM 커널 버퍼 구역.

</details>

```text
[ DMA Architecture with IOMMU Protection ]
┌───────────────────────────────────────────────────────────┐
│ CPU Core (Registers Descriptor & Triggers DMAC Kickoff)   │
├───────────────────────────────────────────────────────────┤
│ System Bus (Bus Grant / Bus Request Control)             │
├───────────────────────────────────────────────────────────┤
│ DMA Controller (DMAC / Bus Master)                        │
│  ├─ Address Register / Byte Counter                       │
│  └─ Scatter-Gather Descriptor Fetch Engine                │
├───────────────────────────────────────────────────────────┤
│ IOMMU (IOVA to PA Translation & Access Permission Check)  │
├───────────────────────────────────────────────────────────┤
│ Main Memory DRAM Buffer (Kernel Page Pinning)             │
└───────────────────────────────────────────────────────────┘
```

| 구성요소 | 역할 및 작동 원리 | 차별점 및 실무 유용성 |
|:---|:---|:---|
| **DMA 제어기 (DMAC)** | 버스 마스터 권한 획득, 주소 증분 및 카운터 차감 전송 | 전송 완결 시까지 CPU 코어 가동 중단 없이 독립 전송 구동 |
| **IOMMU** | IOVA->PA 가상 주소 변환 및 허용되지 않은 메모리 구역 차단 | 고장 장치나 악의적 DMA 하드웨어의 타 메모리 무단 덮어쓰기 파괴 차단 |
| **Scatter-Gather Engine**| 메모리 내 디스크립터 링 버퍼 링크드 리스트 순차 읽기 | 흩어진 4KB 가상 페이지들을 단 1회 전송 명령으로 묶어 연속 인출 |
| **Page Pinning (Lock)** | DMA 버퍼 페이지가 중간에 OS 요구 페이징으로 Swap-out 안되게 고정 | DMA 전송 중 물리 주소가 바뀌는 데이터 오염 현상 예방 |

#### 한줄 요약
- DMAC(Bus Master), IOMMU(주소 변환/보호), Scatter-Gather Engine 및 Kernel Page Pinning 유닛으로 통합 구동됨.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **버퍼 매핑 (Buffer Mapping / Page Pinning)**: DMA 전송 대상 DRAM 페이지를 물리 메모리에 강제 상주(Pinning) 시키고 IOMMU 주소를 구성하는 사전 준비 과정.
- **전송 완료 통지 (Completion Notification)**: DMAC가 지정된 바이트 수를 100% 인출 완료한 직후 CPU 코어로 IRQ 인터럽트 패킷을 발송하는 통지 연산.

</details>

```text
[ CPU Driver DMA Transfer Setup ]
                │
                ▼
   [ 1. Page Pinning & IOMMU Buffer Mapping (IOVA -> PA) ]
                │
                ▼
   [ 2. Write Descriptor (Src, Dst, Len) to RAM & Kickoff DMAC ]
                │
                ▼
   [ 3. DMAC Bus Master Request (HRQ) & Bus Granted (HLDA) ]
                │
                ▼
   [ 4. DMAC Direct Memory Read/Write Operation (Burst / Cycle Steal) ]
                │
                ▼
   [ 5. Transmit Complete ──> Assert IRQ Interrupt & Unpin Page ]
```

### 동작 원리

1. **사전 준비**: 드라이버가 **페이지 고정(Page Pinning)**을 수행하고 **IOMMU** 상에 IOVA-PA 주소 매핑을 할당함.
2. **DMAC Kickoff**: CPU가 **전송 디스크립터**를 메모리에 구성하고 DMAC 레지스터에 시작 주소를 쓰며 기동(Kickoff)함.
3. **버스 획득 및 직접 전송**: DMAC가 CPU로 Bus Request(HRQ)를 보내 버스 제어권을 잡고(**Bus Master**), 메모리와 주변장치 간 직접 전송을 완료함.
4. **인터럽트 완결**: 전송 완료 후 DMAC가 CPU로 **전송 완료 인터럽트(IRQ)**를 발생시키고 버퍼 소유권을 반환함.

#### 한줄 요약
- Page Pinning/IOMMU Mapping -> DMAC Setup & Kickoff -> Bus Master Acquire -> Direct Block Data Transfer -> IRQ Completion & Unpin 순으로 진행됨.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **프로그램 I/O (Programmed I/O, PIO)**: CPU가 IN/OUT 기계어 루프 명령으로 장치 레지스터에서 바이트 데이터를 직접 하나씩 읽어 옮기는 구형 제어 방식.
- **버스트 모드 (Burst Mode DMA)**: DMAC가 버스 제어권을 한 번 잡으면 전체 블록 데이터 전송이 완전히 끝날 때까지 버스를 독점하는 최고속 방식.

</details>

| 비교 항목 | DMA (Direct Memory Access) | PIO (Programmed I/O) | Interrupt-Driven I/O |
|:---|:---|:---|:---|
| **전송 제어 주체** | **DMA 제어기 (DMAC)** | **CPU 코어 (Loop)** | **CPU 코어 (ISR)** |
| **CPU 점유율** | **0%** (설정 및 완료 시만 관여) | **100%** (바쁜 대기 반복) | 전송 시 100% (ISR 구동) |
| **적합 전송 크기** | **대용량 블록** (SSD, NIC, GPU) | 초소형 단발 데이터 | 중소형 불규칙 데이터 |
| **버스 제어 방식** | **Bus Master** (버스 제어권 직접 소유) | Bus Slave | Bus Slave |
| **전송 단위** | **Block (Pages / Sectors)** | Byte / Word | Byte / Word |

#### 한줄 요약
- DMA는 DMAC 버스 마스터 기반 대용량 무지연 블록 전송을 제공하고, PIO 및 Interrupt I/O는 CPU 코어가 바이트 단위 전송을 직접 전담함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **캐시 일관성 (Cache Coherency / Cache Clean & Invalidate)**: DMAC가 메모리를 덮어썼을 때 CPU L1/L2 캐시 상의 구버전 데이터(Stale Data)를 무효화(Invalidate)하거나 쓰기 전 캐시를 DRAM에 Flush(Clean)하는 동기화 메커니즘.
- **버퍼 소유권 (Buffer Ownership)**: DMA 전송 중 CPU와 DMAC가 동일 메모리 버퍼를 동시 쓰기(Write Race)하지 않도록 락을 통해 소유권을 명확히 분리 제어하는 규칙.

</details>

| 문제 및 병목 원인 | 실무적 대책 및 해결 방안 | 기대 효과 |
|:---|:---|:---|
| DMAC가 DRAM을 갱신했으나 CPU 캐시에 구버전 데이터가 남아 데이터 파손 | DMA 읽기 전 **Cache Clean**, DMA 완료 후 **Cache Invalidate** | CPU-DMA 간 캐시 일관성(Coherency) 완벽 보장 |
| DMA 전송 진행 도중 OS 요구 페이징 스왑으로 물리 메모리 주소 변경 | 커널 레벨 **Page Pinning (`get_user_pages()`)** 강제 적용 | DMA 전송 도중 메모리 주소 이탈 파손 방지 |
| 고장 난 PCIe 카드나 악의적 펌웨어가 커널 메모리를 DMA로 파괴 | **IOMMU** 기반 DMA 주소 영역 격리 및 접근 권한 필터링 | 하드웨어 레벨 메모리 무단 침범 예방 |
| DMAC가 버스를 장시간 독점하여 CPU의 메인 메모리 인출 정지 | **사이클 스티어링 (Cycle Stealing)** 및 버스 쿼터 타임아웃 설정 | CPU 파이프라인 정지 예방 및 버스 대역폭 공정 분배 |

#### 한줄 요약
- Cache Clean/Invalidate(일관성 보장), Page Pinning(물리 주소 고정), IOMMU 영역 격리 및 Cycle Stealing 기법을 구동함.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **DMA 최적화 선택 기준 (DMA Optimization Criteria)**: 대상 입출력 시스템의 전송 블록 크기, IOMMU 보안 정책, CPU 캐시 구조(Snooping 하드웨어 지원 여부)를 종합 평가하여 DMA 동작 모드 및 캐시 동기화 파라미터를 확정하는 프레임워크.

</details>

- **DMA 최적화 선택 기준 (DMA Optimization Criteria)**에 의거하여 SSD 및 초고속 네트워크(100GbE) 인프라 구축 시 CPU 복사 전송 오버헤드를 완전 차단하기 위해 **DMAC 버스 마스터 기반 DMA** 아키텍처를 필수로 채택하고, 하드웨어 **IOMMU 주소 격리**, **Page Pinning** 및 **Cache Clean/Invalidate** 동기화 제어 체계 적용 필수.

#### 한줄 요약
- CPU 복사 전송 소거를 위한 DMAC 버스 마스터 DMA 아키텍처 채택 및 IOMMU/Cache Clean/Invalidate 동기화 체계 적용.
