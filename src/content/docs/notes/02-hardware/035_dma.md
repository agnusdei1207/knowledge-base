## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: 전용 엔진이 장치와 메모리 사이를 직접 전송하는 기법이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 프로그램 명령을 실행하는 장치이다.
- **입출력(Input/Output, I/O)**: 호스트와 장치 사이의 데이터를 전달하는 체계이다.
- **CPU 복사 비용**: CPU가 I/O 데이터를 직접 옮기며 소비하는 시간과 대역폭이다.

</details>

- 정의/개념: 전용 버스 마스터가 I/O 장치와 주기억장치 사이의 데이터를 직접 옮기는 **DMA** 방식이다.
- 배경/필요성: CPU가 대량 I/O 데이터를 직접 복사하면 명령 실행 시간과 추가 메모리 대역폭 소모가 발생한다.

#### 한줄 요약

- CPU가 주소·길이·방향을 설정하면 DMA 엔진이 장치와 메모리 사이의 데이터를 직접 전송하고 완료만 통지한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **버스 마스터**: 인터커넥트에서 메모리 읽기•쓰기 트랜잭션을 직접 시작하는 주체이다.
- **전송 디스크립터**: 전용 전송 엔진이 사용할 주소•길이•방향을 기록한 작업 명세이다.
- **분산 수집**: 흩어진 여러 메모리 버퍼를 하나의 디스크립터 목록으로 전송하는 방식이다.

</details>

- 큰 블록에서 설정 비용을 상쇄하는 **CPU 복사 비용** 절감이 핵심이다.
- DMA 컨트롤러의 **버스 마스터** 전송이 핵심이다.
- 비연속 버퍼를 한 작업으로 전송하는 **분산 수집**이 핵심이다.

#### 한줄 요약

- 대용량 또는 비연속 버퍼 전송에서는 DMA 설정 비용보다 CPU 복사 절감 이득이 커진다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **DMA 드라이버**: 전송 명세와 엔진 시작•완료•오류를 처리하는 소프트웨어이다.
- **DMA 컨트롤러**: 버스 마스터로 장치와 주기억장치 사이의 블록을 옮기는 회로이다.
- **주기억장치 버퍼**: 데이터와 DMA 디스크립터를 장치가 접근하도록 보관하는 영역이다.

</details>

```text
                       [CPU•DMA 드라이버]
                                |
[I/O 장치] ----- [DMA 컨트롤러] ----- [주기억장치]
```

선의 의미: 선은 DMA 컨트롤러를 중심으로 제어 경계와 장치•메모리 데이터 경계가 결합되는 정적 연결 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| CPU•DMA 드라이버 | 전송 명세•시작•완료 처리 |
| DMA 컨트롤러 | 장치•메모리 블록 전송 |
| I/O 장치 | 데이터 출발지•목적지 제공 |
| 주기억장치 | 데이터•디스크립터 보관 |

#### 한줄 요약

- CPU가 전송 명세를 제출하면 DMA 컨트롤러가 장치와 메모리 사이의 블록을 옮긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **버퍼 매핑**: 메모리 버퍼를 장치 주소 공간에 연결하고 접근 권한을 설정하는 작업이다.
- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: DMA 주소를 변환•격리하는 하드웨어이다.
- **전송 완료 통지**: 블록 이동 완료를 CPU 드라이버에 알리는 인터럽트나 큐 상태이다.
- **버퍼 매핑·권한 설정**: DMA 버퍼를 장치 주소 공간에 연결하고 허용 접근을 정하는 단계이다.
- **전송 디스크립터 등록·시작**: 주소·길이·방향을 기록하고 DMA 엔진을 실행하는 단계이다.
- **장치 주소 변환·접근 판정**: 장치 주소를 변환하고 읽기·쓰기 권한을 확인하는 단계이다.
- **장치·메모리 블록 전송**: DMA 엔진이 지정 블록을 장치와 주기억장치 사이에서 옮기는 단계이다.
- **완료 통지·버퍼 인계**: 완료를 CPU에 알리고 동기화된 버퍼 소유권을 돌려주는 단계이다.

</details>

```text
                      [CPU I/O 요청]
                              |
                 1. IOMMU 버퍼 매핑•권한 설정
                              |
                 2. 전송 디스크립터 등록•시작
                              |
                       [DMA 컨트롤러]
                              |
              +--------------------------------+
              | 반복: 디스크립터 잔여 블록    |
              | 3. 장치 주소 변환•접근 판정  |
              | 4. 장치•메모리 블록 전송     |
              +--------------------------------+
                              |
                       [완료 상태 기록]
                              |
                    5. 완료 통지•버퍼 인계
```

### 동작 원리

1. **버퍼 매핑·권한 설정**: DMA 버퍼를 장치 주소 공간에 연결하고 IOMMU 사용 시 접근 가능한 범위와 방향을 제한한다.
2. **전송 디스크립터 등록·시작**: 출발지·목적지 주소, 길이, 방향을 기록하고 DMA 엔진을 실행한다.
3. **장치 주소 변환·접근 판정**: 각 디스크립터의 장치 주소를 변환하고 읽기·쓰기 권한을 확인한다.
4. **장치·메모리 블록 전송**: DMA 엔진이 CPU 복사 없이 지정 블록을 장치와 주기억장치 사이에서 이동한다.
5. **완료 통지·버퍼 인계**: 완료 상태를 기록하고 CPU에 알린 뒤 동기화된 버퍼 소유권을 드라이버에 반환한다.

#### 한줄 요약

- CPU는 버퍼 권한과 전송 디스크립터를 설정하고, DMA 엔진은 직접 전송을 수행한 뒤 완료 상태와 버퍼 소유권을 반환한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **인터럽트 입출력(Interrupt Input/Output, 인터럽트 I/O)**: 장치가 준비될 때마다 중앙 처리 장치(Central Processing Unit, CPU)에 알리고 CPU가 데이터 전송을 수행하는 방식이다.
- **프로그램 입출력(Programmed Input/Output, 프로그램 I/O)**: CPU가 장치 상태를 반복 확인하면서 데이터까지 직접 옮기는 방식이다.
- **설정 비용**: 전송 디스크립터•주소 매핑•동기화를 준비하는 데 드는 고정 처리 시간이다.

</details>

| I/O 방식 | DMA | 인터럽트 I/O | 프로그램 I/O |
|:---|:---|:---|:---|
| 적용 기준 | 대용량•연속•분산 블록 | 비정기 소량 이벤트 | 매우 짧고 단순한 I/O |
| 핵심 특징 | **DMA** 엔진의 블록 직접 전송 | **인터럽트 I/O**의 CPU 전송 | **프로그램 I/O**의 직접 전송 |
| 한계 | 설정•동기화•디스크립터 관리 | 인터럽트•문맥 전환 | 바쁜 대기•CPU 복사 |

> 요약: 대량은 DMA, 소량은 인터럽트 I/O가 핵심이다.

#### 한줄 요약

- 설정 비용을 상쇄하는 대용량·분산 블록은 DMA가 유리하고, 비정기 소량 전송은 인터럽트 I/O가 단순하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **캐시 clean**: CPU 수정분을 메모리에 반영하는 동작이다.
- **캐시 invalidate**: DMA가 바꾼 메모리의 오래된 캐시 사본을 버리는 동작이다.
- **버퍼 소유권**: CPU와 장치 중 누가 버퍼를 읽거나 쓸 수 있는지 나타내는 접근 상태이다.
- **메모리 장벽**: 버퍼 데이터와 장치 레지스터 접근이 정해진 순서로 관측되도록 보장하는 명령이다.
- **비휘발성 메모리 익스프레스(Non-Volatile Memory Express, NVMe)**: DMA로 저장장치와 호스트 메모리 사이를 전송하는 인터페이스이다.
- **멱등 재시도**: 부분 실패 뒤 같은 전송을 다시 실행해도 결과가 중복 적용되지 않게 하는 복구 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비일관 캐시에서 동기화를 생략해 CPU·장치 데이터 불일치 | 전송 방향에 맞는 **캐시 clean·캐시 invalidate·메모리 장벽** 적용 | DMA 시작·완료 시점의 최신 데이터 보장 |
| DMA 완료 전에 CPU가 버퍼를 재사용해 동시 접근·데이터 손상 | **버퍼 소유권**과 완료 동기화·참조 수명 명시 | CPU와 장치의 접근 시점 분리로 버퍼 손상 방지 |
| 잘못된 디스크립터가 임의 메모리를 가리켜 주소 공간 침범 | **IOMMU** 주소 범위·접근 권한 검증과 오류 기록 | 장치별 허용 영역 밖 접근 차단 |
| 큰 버스트가 공유 버스를 독점하거나 중간 오류로 부분 전송 | 전송 크기·우선순위 조정과 잔여 길이 기반 **멱등 재시도** | 대역폭 공정성과 부분 실패 복구성 향상 |

> 사례: NVMe의 DMA 버퍼 접근 범위를 제한하는 **IOMMU**

#### 한줄 요약

- IOMMU로 장치의 DMA 주소 범위를 제한하고 버퍼 소유권을 완료 시점에 인계해 메모리 침범과 동시 재사용을 방지한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **대용량 블록 전송**: 설정 비용보다 CPU 복사 절감 이득이 큰 데이터 이동이다.
- **비정기 소량 I/O**: DMA 준비보다 인터럽트 처리가 간단한 소량 작업이다.
- **전송 방식 선택 기준**: 전송 크기와 설정 비용을 비교해 DMA와 인터럽트 I/O를 고르는 기준이다.

</details>

- **전송 방식 선택 기준**에 따라 **대용량 블록 전송**에는 **DMA**, **비정기 소량 I/O**에는 **인터럽트 I/O**를 선택한다.

#### 한줄 요약

- CPU 복사 절감 이득이 버퍼 매핑과 디스크립터 설정 비용보다 클 때 DMA를 사용하고, IOMMU로 접근 범위를 격리한다.
