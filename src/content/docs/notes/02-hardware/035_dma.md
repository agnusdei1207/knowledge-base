## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU의 직접적인 개입 없이 전용 DMA 제어기(DMAC)가 버스 마스터(Bus Master) 권한을 획득하여 주기억장치(DRAM)와 고속 주변장치 간에 블록 데이터를 고속으로 직접 전송하는 하드웨어 기술.
- **복사 오버헤드(Copy Overhead)**: CPU 코어가 레지스터를 통해 데이터를 한 워드씩 루프로 복사할 때 연산 파이프라인과 버스가 낭비되는 성능 저하 현상.
- **버스 마스터(Bus Master)**: CPU 대신 시스템 주소/데이터 버스의 제어권을 획득하여 읽기·쓰기 트랜잭션을 독자적으로 주도할 수 있는 장치.

</details>

- 정의/개념: 전용 제어기가 **버스 마스터(Bus Master)** 권한을 위임받아 CPU 개입 없이 메모리와 주변장치 간 블록 데이터를 직접 전송하는 **직접 메모리 접근(DMA) 아키텍처**
- 배경/필요성: CPU를 경유하는 프로그램 I/O 및 인터럽트 방식에 따른 **대용량 데이터 전송 시 CPU 연산 병목 및 버스 낭비 극복**

#### 한줄 요약
- DMA는 CPU 대신 전용 제어기가 버스를 주도하여 메모리와 장치 간 대용량 데이터를 직접 전송함으로써 CPU 연산력을 보존한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사이클 스틸링(Cycle Stealing)**: DMA 제어기가 CPU의 메모리 비접근 유휴 사이클을 1워드 단위로 가로채어 전송함으로써 CPU 연산 중단을 최소화하는 모드.
- **버스트 모드(Burst Mode)**: 버스 제어권을 한 번 선점한 후 데이터 블록 전체를 연속해서 최고속으로 전송하는 모드.
- **산란-집적(Scatter-Gather)**: 물리적으로 흩어진 복수의 불연속 메모리 버퍼들을 연결 리스트(Descriptor)로 묶어 단 1회의 DMA 명령으로 연속 전송하는 기법.

</details>

- CPU 부하 제거: 전송 시작 시 주소/크기 설정과 완료 시 1회의 인터럽트 처리만 CPU가 담당하고 **실제 전송 과정에서는 CPU 개입 0%**
- 버스 제어권 중재: **버스 요청(BR)**과 **버스 승인(BG)** 핸드셰이크를 통해 CPU와 버스 사용권을 안전하게 교환
- 불연속 버퍼 가속: **산란-집적(Scatter-Gather)** DMA를 지원하여 가상 메모리의 비연속 물리 프레임들을 단일 트랜잭션으로 일괄 전송

#### 한줄 요약
- 버스 마스터링으로 CPU 부하를 제거하고, 사이클 스틸링/버스트 모드로 전송 효율을 조율하며, 산란-집적으로 비연속 버퍼를 고속 전송한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주소 레지스터(Address Register)**: 전송할 메모리의 물리 시작 주소를 보관하고 전송 시마다 주소 크기만큼 자동 증가/감소하는 레지스터.
- **카운트 레지스터(Count Register)**: 전송할 총 바이트(또는 워드) 수를 보관하고 전송마다 1씩 감소하여 0 도달 시 완료 인터럽트를 발생하는 레지스터.
- **버스 요청/승인 신호(BR / BG)**: DMAC가 CPU에 버스 권한을 요청(BR)하고 CPU가 버스를 양보(BG)하는 하드웨어 제어 신호.

</details>

```text
[CPU 코어] ── (전송 시작 설정 / 완료 인터럽트)
    │ (BR / BG 버스 중재 핸드셰이크)
    ▼
[DMA 제어기 (DMA Controller)]
 ├─ 주소 레지스터 (Memory Address Register: 전송마다 자동 증가)
 ├─ 카운트 레지스터 (Byte Count Register: 0 도달 시 완료)
 ├─ 제어 및 상태 레지스터 (방향 R/W, 버스트/스틸링 모드, 에러 플래그)
 └─ [산란-집적 디스크립터 엔진 (Scatter-Gather Engine)]
    │
    ▼ (시스템 버스 / PCIe 버스 직결)
 ┌────────────────────────────────────────────────────────┐
 │ [주기억장치 (DRAM)] ◄══════ (직접 블록 데이터 전송) ══════► [고속 주변장치 (NVMe / NIC)] │
 └────────────────────────────────────────────────────────┘
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 이중선(`═`)은 CPU를 거치지 않고 DRAM과 주변장치가 직접 통신하는 데이터 경로임

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **주소 레지스터** | DMA 제어기 내부 | 전송 대상 메모리 물리 주소 보관 및 바이트 전송 시 자동 증감 | 64비트 주소 지원 |
| **카운트 레지스터** | DMA 제어기 내부 | 잔여 전송 바이트 수 계수 및 0 도달 시 **완료 인터럽트 발생** | 카운트 다운 레지스터 |
| **제어/상태 레지스터**| DMA 제어기 내부 | 전송 방향(Mem-to-Dev, Dev-to-Mem), 전송 모드 설정 | MMIO 제어 인터페이스 |
| **산란-집적 엔진** | DMA 제어기 내부 | 메모리 상의 **디스크립터 체인 리스트를 자체 순회** | 불연속 페이지 일괄 전송 |
| **IOMMU** | 칩셋 / CPU 내부 | DMA 장치의 가상 주소를 물리 주소로 변환하고 메모리 보호 | DMA 악성 접근 격리 |

#### 한줄 요약
- DMA 시스템은 주소/카운트/제어 레지스터를 갖춘 DMAC 제어기와 버스 중재 회로, 산란-집적 엔진 및 IOMMU로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IOMMU(Input-Output Memory Management Unit)**: 주변 장치의 DMA 요청 주소를 가상 주소에서 물리 주소로 변환하고 비인가 메모리 접근을 차단하는 보안 하드웨어.

</details>

```text
1. CPU가 DMAC 레지스터에 전송 시작 주소, 바이트 수, 전송 방향 설정
                      │
                      ▼
2. DMAC: CPU로 버스 요청 신호(BR: Bus Request) 전송
                      │
                      ▼
3. CPU: 현재 버스 사이클 완료 후 버스 승인 신호(BG: Bus Grant) 반환 및 버스 절체 (High-Z)
                      │
                      ▼
4. DMAC가 버스 마스터(Bus Master) 권한 획득 ➔ 전송 모드에 따른 블록 전송 수행
   ┌──────────────────┴──────────────────┐
[ 버스트 모드 (Burst Mode) ]          [ 사이클 스틸링 (Cycle Stealing) ]
   │                                     │
   ▼                                     ▼
5. 버스를 연속 독점하여 전체 블록 전송 6. 1워드 전송마다 버스를 CPU에 즉시 반환/재요청
   │                                     │
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 카운트 레지스터 0 도달 ➔ 버스 반환 및 CPU로 완료 인터럽트(IRQ) 발행
```

분기 결과: **버스트 모드는** 최대 전송 속도를 내나 CPU 메모리 접근을 차단하고, **사이클 스틸링은** CPU 연산과 버스를 균형 있게 공유함

#### 한줄 요약
- 초기화 ➔ BR/BG 버스 중재 ➔ 버스트/스틸링 전송 ➔ 카운트 완료 ➔ 버스 반환 및 IRQ 통지의 5단계로 동작한다.

## Ⅴ. 종류 및 비교

| DMA 전송 모드 | 버스트 모드 (Burst Mode) | 사이클 스틸링 (Cycle Stealing) | 디맨드 모드 (Demand Mode) |
|:---|:---|:---|:---|
| 버스 점유 방식 | **데이터 블록 전체를 전송할 때까지 버스 연속 독점** | **1워드 전송 후 버스를 즉시 CPU에 반환** | 주변 장치의 DREQ 신호가 활성인 동안만 버스 점유 |
| 전송 처리량 | **최고 (버스 중재 오버헤드 1회만 발생)** | 중간 (전송 워드마다 중재 오버헤드 발생) | 장치 데이터 준비 속도에 종속 |
| CPU 연산 영향 | **CPU 메모리 접근이 전송 동안 일시 정지됨** | **CPU 연산과 메모리 접근이 거의 방해받지 않음** | 가변적 (장치 상태에 따라 유동적) |
| 주요 적용 분야 | **NVMe SSD 고속 읽기/쓰기, 고해상도 그래픽 버퍼** | 키보드/마우스, 실시간 센서 데이터 수집 | 저속 UART, 가변 속도 스트리밍 장치 |

#### 한줄 요약
- 최고 속도의 대용량 전송에는 버스트 모드가 적합하고, CPU 응답성을 유지해야 하는 환경에는 사이클 스틸링이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 정리 및 무효화(Cache Clean & Invalidate)**: DMA 읽기 전 더티 캐시를 메모리에 반영(Clean)하고, DMA 쓰기 후 CPU의 구 캐시 라인을 무효화(Invalidate)하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DMA 전송 데이터와 CPU 캐시 불일치로 데이터 오염 발생 | **드라이버 레벨 캐시 정리(Clean) / 무효화(Invalidate) 수행** | CPU-메모리-장치 간 데이터 정합성 100% 보장 |
| 가상 메모리 페이징으로 인한 불연속 물리 메모리 전송 복잡도 | **산란-집적(Scatter-Gather Descriptor) DMA 엔진 활용** | 메모리 재복사 없이 불연속 프레임 일괄 고속 전송 |
| 악의적 장치의 DMA를 통한 커널 메모리 탈취 및 침범 위험 | **하드웨어 IOMMU(Intel VT-d, ARM SMMU) 주소 격리 적용** | 비인가 메모리 접근 차단 및 가상화 보안 완성 |

#### 한줄 요약
- 실무에서는 캐시 플러시/무효화로 일관성을 유지하고, 산란-집적으로 비연속 페이지를 처리하며, IOMMU로 DMA 보안을 격리한다.

## Ⅶ. 결론

- 고성능 컴퓨팅 및 대용량 I/O 서브시스템의 성능을 극대화하기 위해 **버스 마스터링과 산란-집적(Scatter-Gather)을 지원하는 고성능 DMA 아키텍처를 표준 채택**하고, 데이터 정합성을 보장하기 위해 **하드웨어 일관성 버스 및 드라이버 캐시 플러시 메커니즘**을 적용하며, 가상화 및 디바이스 보안을 위해 **IOMMU 기반 주소 격리 체계**를 필수 구축하는 고효율 DMA 시스템 설계 확립

#### 한줄 요약
- DMA는 CPU 부하를 없애는 핵심 전송 기술이며, 산란-집적과 캐시 정합성 및 IOMMU 보안과의 결합을 통해 완성된다.
