## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린의 분류(Flynn's Taxonomy)**: 마이클 플린(Michael J. Flynn)이 제안한 컴퓨터 아키텍처 분류 체계로, CPU의 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 단일(Single)·다중(Multiple) 조합에 따라 시스템을 4가지 기본 범주로 분류.
- **명령어 스트림(Instruction Stream, IS)**: 프로세서의 제어 장치(Control Unit, CU)에 의해 메모리에서 순차적으로 인출·해독되는 기계어 명령어의 흐름.
- **데이터 스트림(Data Stream, DS)**: 처리 장치(Processing Unit, PU / ALU)에 입력되어 명령어에 의해 조작되는 피연산자 데이터의 흐름.

</details>

- 정의/개념: 컴퓨터 시스템의 병렬성 구조를 **명령어 스트림(IS)과 데이터 스트림(DS)**의 단일(Single)/다중(Multiple) 수량을 기준으로 4대 기본 아키텍처로 분류한 **플린의 분류(Flynn's Taxonomy)** 체계
- 배경/필요성: 다양하게 발전하는 컴퓨터 병렬 처리 시스템의 하드웨어 구조를 단일 성능 지표만으로는 체계적으로 분류·평가하기 어려운 **아키텍처 체계화의 한계 극복 및 병렬 컴퓨팅 설계 표준 분류 체계 확립 필요성 증대**

#### 한줄 요약
- 플린의 분류는 명령어와 데이터의 흐름 수를 2×2 매트릭스로 조합하여 SISD, SIMD, MISD, MIMD로 병렬성을 규정하는 고전 표준 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 병렬성(Data Parallelism)**: 단일 연산 명령어를 대규모 배열이나 행렬의 개별 데이터 요소들에 동시에 적용하는 병렬 처리 형태.
- **태스크 병렬성(Task Parallelism)**: 서로 다른 독립된 명령어 코드와 제어 흐름(스레드/프로세스)을 다수의 코어에서 동시에 비동기 실행하는 형태.

</details>

- 직관적인 2×2 매트릭스 분류: SISD, SIMD, MISD, MIMD의 4개 상호 배타적 영역으로 컴퓨터 시스템의 **하드웨어 제어 경계 정의**
- 병렬성 유형의 명확화: 단일 명령어로 대량 데이터를 다루는 **데이터 병렬성(SIMD)**과 독립 코어가 협업하는 **태스크 병렬성(MIMD)**의 본질적 차이 규명
- 계층적 하이브리드 확장성: 현대 슈퍼컴퓨터 및 GPU 서버의 노드 간 MIMD + 노드 내 SIMT/SIMD 복합 아키텍처 분석의 **이론적 토대 제공**

#### 한줄 요약
- 2×2 매트릭스로 제어와 데이터의 병렬 구조를 명확히 정의하며, 현대 하이브리드 시스템 분석의 기반이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어 장치(Control Unit, CU)**: 메모리로부터 명령어를 인출(Fetch)하고 해독(Decode)하여 처리 장치에 제어 신호를 인가하는 하드웨어 유닛.
- **처리 장치(Processing Unit, PU)**: 제어 장치의 지시에 따라 산술 논리 연산(ALU)을 직접 실행하는 하드웨어 연산 레인.

</details>

```text
[플린의 분류 4대 아키텍처]
  │
  ├─ [단일 명령어 스트림군] (Single IS, 단일 CU)
  │     ├─ [SISD 아키텍처] (Single IS, Single DS)
  │     │     └─ (고전 폰 노이만 단일 코어, 순차 실행)
  │     │
  │     └─ [SIMD 아키텍처] (Single IS, Multiple DS)
  │           └─ (벡터 프로세서, GPU SIMT, 데이터 병렬)
  │
  └─ [다중 명령어 스트림군] (Multiple IS, 복수 독립 CU)
        ├─ [MISD 아키텍처] (Multiple IS, Single DS)
        │     └─ (우주/원전 중복 다수결, 파이프라인 수축)
        │
        └─ [MIMD 아키텍처] (Multiple IS, Multiple DS)
              └─ (멀티코어 CPU, 분산 클러스터, 태스크 병렬)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| SISD | 단일 명령어로 단일 데이터의 순차 처리 |
| SIMD | 단일 명령어로 다중 데이터의 데이터 병렬 처리 |
| MISD | 다중 명령어로 단일 데이터의 중복 처리 |
| MIMD | 다중 명령어로 다중 데이터의 비동기 분산 처리 |

#### 한줄 요약
- 명령어 흐름과 데이터 흐름 두 축만으로 칸을 가르므로 SISD의 제어부를 그대로 두고 연산기만 늘린 것이 SIMD, 제어부까지 복제해 그 비용을 치른 것이 MIMD가 되며, MISD 칸은 같은 데이터를 중복 처리하는 특수 용도로만 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분석 관점(Observation Boundary)**: 코어 레벨, 프로세서 칩 레벨, 랙 클러스터 레벨 등 병렬성을 판정하는 시스템의 관찰 계층 기준.

</details>

```text
[분석 대상 하드웨어 계층 경계 설정: 코어 내부 / 칩 전체 / 분산 클러스터]
                                  │
                                  ▼
1. 독립된 프로그램 카운터(PC)와 제어 장치(CU) 수 판정
    ┌─────────────────────────────┴─────────────────────────────┐
 [ 단일 제어 장치 (Single IS) ]              [ 복수 독립 제어 장치 (Multiple IS) ]
    │                                           │
    ▼                                           ▼
2. 단일 명령어가 처리하는 데이터 수는?          2. 각 독립 제어 흐름이 다루는 데이터는?
    ┌─────────────┴─────────────┐               ┌─────────────┴─────────────┐
 [ 단일 데이터 ]             [ 다중 데이터 ] [ 동일 데이터 중복 ]        [ 독립 데이터 분산 ]
    │                           │               │                           │
    ▼                           ▼               ▼                           ▼
3. SISD 아키텍처             3. SIMD 아키텍처 3. MISD 아키텍처            3. MIMD 아키텍처
    │                           │               │                           │
    └───────────────────────────┴───────┬───────┴───────────────────────────┘
                                        │
                                        ▼
4. 하드웨어 관찰 계층(SoC 레벨 MIMD + 내부 코어 레벨 SIMD) 계층적 통합
                                        │
                                        ▼
5. 현대 이종 컴퓨팅(Heterogeneous Computing) 하이브리드 토폴로지 최종 확정
```

분기 결과: **제어 장치** 수에서 갈리면 PC와 제어 회로를 복제하는 비용을, 데이터 레인 수에서 갈리면 연산 레인을 넓히는 비용을 치르며 4대 기본 영역이 나뉘고, 현대 시스템은 두 비용을 계층별로 나눠 부담해 계층적 하이브리드로 귀결됨

**동작 원리**

1. **관찰 경계 획정**: 분석 대상 하드웨어의 관찰 경계를 시스템 수준(SoC, 노드, 클러스터) 또는 코어 내부 수준으로 명확히 획정
2. **독립 제어 장치 수 판별**: 시스템 내에 독립적인 프로그램 카운터(PC)를 가지고 독자적으로 명령어를 인출·해독하는 제어 유닛(CU) 개수 판별
3. **데이터 처리 레인 검증**: 제어 신호 인가 시 ALU가 단일 메모리 워드만 처리하는지, 다중 레지스터 레인을 통해 벡터 데이터를 동시 처리하는지 검증
4. **명령어-데이터 매핑 판정**: 독립 제어 장치가 여러 개인 경우 각 코어가 동일 데이터를 중복 검증하는지(MISD), 서로 다른 메모리 영역의 독립 태스크를 실행하는지(MIMD) 판정
5. **계층적 하이브리드 통합**: 노드 레벨의 MIMD 분산 환경과 가속기 코어 내부의 SIMD/SIMT 데이터 병렬성을 계층적으로 결합하여 최적 하이브리드 설계 도출

#### 한줄 요약
- 같은 하드웨어라도 코어 내부와 칩 전체, 클러스터 중 어느 경계를 관찰하느냐에 따라 판정이 달라지므로, 분류명을 대기 전에 그 분류가 전제한 관찰 계층을 먼저 밝혀야 한다.

## Ⅴ. 종류 및 비교

| 대상 구분 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 적용 기준 | 단순 단일 스레드 제어 로직 시 | 대규모 동종 데이터 병렬 연산 시 | 극단적 고신뢰 결함 허용 시스템 구축 시 | 비동기 멀티스레드 및 분산 서버 구동 시 |
| 핵심 특징 | 단일 제어 장치(CU) 및 단일 연산기(ALU), 고전 폰 노이만 순차 파이프라인 | 단일 CU 기반 다중 ALU 동기 구동, **데이터 병렬성 극대화**, 벡터/GPU 아키텍처 | 다중 CU가 단일 데이터 스트림에 상이한 연산 적용, 우주항공 다중 검증 시스템 | 코어별 독립 CU/PU 탑재, **비동기 태스크 병렬성**, 멀티코어 및 분산 클러스터 |
| 한계 | 명령어 수준 병렬성(ILP) 한계, 클록 주파수 증폭 발열 벽 직면 | 조건 분기(if-else) 시 연산 레인 유휴 발생(Divergence), 비정형 데이터 비효율 | 하드웨어 복잡도 대비 상용 구현 극소수, 제어 간 동기화 오버헤드 과다 | 스레드 간 동기화 및 락 경합, 캐시 일관성 유지 트래픽 폭증 |

#### 한줄 요약
- 정형 대량 데이터 연산에는 SIMD가, 독립 멀티태스킹과 분산 환경에는 MIMD가 최적의 아키텍처이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: SIMD의 데이터 레인 구조 위에 스레드 단위의 프로그래밍 추상화와 하드웨어 워프 스케줄링을 결합한 확장 모델.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템 관찰 계층(코어 vs 칩) 혼동으로 인한 아키텍처 분석 오류 | **계층적 분석** 체계 적용 (SoC 수준 MIMD + 코어 내 SIMD) | 시스템 병렬 구조의 정확한 파악 및 최적화 |
| SIMD/SIMT 구조에서 if-else 조건문으로 인한 성능 급락 | **브랜치 프리 마스킹** 알고리즘 적용 | 연산 레인 유휴 제거 및 처리량 극대화 |
| MIMD 환경에서 코어 수 증가에 따른 캐시 일관성 및 락 병목 | **디렉터리 기반 일관성** 및 **락-프리 큐** 적용 | 코어 확장 시 선형적 처리 성능 확보 |

#### 한줄 요약
- 실무에서는 계층적 하이브리드 관점으로 시스템을 분석하고, SIMD의 분기 발산과 MIMD의 락 경합을 방지해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **명령어 수준 병렬성(Instruction-Level Parallelism, ILP)**: 단일 프로세서 파이프라인 내부에서 독립적인 명령어들을 동시에 중첩 실행하는 마이크로아키텍처 병렬화 기법.
- **분기 발산(Branch Divergence)**: SIMD/SIMT 아키텍처에서 단일 워프 내 스레드들이 서로 다른 조건 분기 경로로 갈라져 직렬화 실행되는 성능 저하 현상.

</details>

- **다계층 하이브리드 병렬 패브릭 진화**: 고전적 4분류의 단일 경계를 넘어, 노드 클러스터 레벨의 분산 MIMD 환경과 온칩 레벨의 대규모 SIMD/SIMT 및 명령어 수준 병렬성(Instruction-Level Parallelism, ILP)이 결합된 이종 복합 구조로의 진화 추세.
- **실무 병렬성 분할 및 매핑 통찰**: 워크로드의 제어 분기 빈도와 연산 밀도를 정량 분석하여, 분기 발산(Branch Divergence) 손실을 억제하고 데이터·태스크 병렬성 비율에 최적화된 계층별 프로세서 매핑 전략 수립 필수.

#### 한줄 요약
- 노드 레벨 MIMD와 온칩 SIMD/SIMT가 융합된 다계층 패브릭으로 진화하고 있으며, 분기 발산 억제와 ILP 추출을 결합한 워크로드 매핑 최적화가 핵심이다.
