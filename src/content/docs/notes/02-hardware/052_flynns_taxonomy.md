## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린 분류(Flynn's Taxonomy)**: 마이클 플린(Michael J. Flynn)이 제안한 컴퓨터 구조 분류 체계로, 명령어 스트림(IS)과 데이터 스트림(DS)의 단일(Single)·다중(Multiple) 조합에 따라 시스템을 4가지로 분류.
- **명령어 스트림(Instruction Stream, IS)**: 제어 장치(CU)에 의해 순차적으로 인출·디코딩되어 실행되는 일련의 기계어 명령어 흐름.
- **데이터 스트림(Data Stream, DS)**: 연산 장치(PU/ALU)에 입력되어 명령어에 의해 조작되는 피연산자 데이터의 흐름.

</details>

- 정의/개념: **명령어 스트림(IS)** 및 **데이터 스트림(DS)**의 단일·다중 조합에 기반한 4대 컴퓨터 구조 분류 체계
- 배경/필요성: 단순 코어 수 집계로는 **제어 흐름과 데이터 병렬성 간 아키텍처 구조 차이 식별 불가**

#### 한줄 요약
- 플린 분류는 명령어와 데이터의 흐름 수(Single/Multiple)를 기준으로 컴퓨터 시스템의 병렬성 구조를 정의하는 기본 분류 체계다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 병렬성(Data Parallelism)**: 동일한 연산 명령어를 대규모 데이터 배열 또는 행렬의 각 요소에 병렬 적용하는 구조.
- **태스크 병렬성(Task Parallelism)**: 서로 다른 독립된 명령어 코드 및 제어 흐름(스레드/프로세스)을 다중 코어에서 동시 실행하는 구조.

</details>

- 2×2 매트릭스 조합으로 병렬 아키텍처를 상호 배타적으로 명확히 분류
- **데이터 병렬성** 및 **태스크 병렬성**의 하드웨어 구현 경계 정의
- 현대 멀티코어·GPU 등의 **하이브리드 계층 구조** 분석 기준 제공

#### 한줄 요약
- 명령어와 데이터 축의 2×2 조합을 통해 SISD, SIMD, MISD, MIMD로 직관적인 병렬 처리 분류 기준을 제시한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어 장치(Control Unit, CU)**: 메모리로부터 명령어를 인출하고 디코딩하여 연산 장치에 제어 신호를 인가하는 하드웨어 유닛.
- **처리 장치(Processing Unit, PU)**: 제어 장치의 지시에 따라 산술 논리 연산(ALU)을 직접 실행하는 하드웨어 연산 유닛.

</details>

```text
[플린 분류 2×2 매트릭스]
|-- 단일 명령어 (SI)
|   |-- 단일 데이터 (SD) -> SISD (전통적 단일 코어 CPU)
|   `-- 다중 데이터 (MD) -> SIMD (벡터 유닛·GPU 셰이더)
`-- 다중 명령어 (MI)
    |-- 단일 데이터 (SD) -> MISD (다중 검증 파이프라인)
    `-- 다중 데이터 (MD) -> MIMD (멀티코어 CPU·분산 클러스터)
```

선의 의미: 계층 및 매트릭스 분류 관계

| 구성요소 | 책임 |
|:---|:---|
| SISD | 단일 **제어 장치(CU)**가 단일 **처리 장치(PU)**를 제어하여 직렬 순차 처리 |
| SIMD | 단일 CU가 다수의 PU 데이터 레인에 동일 명령어를 브로드캐스트하여 동시 실행 |
| MISD | 다수의 독립 CU가 단일 데이터 스트림에 서로 다른 명령어를 인가하는 중복 검증 구조 |
| MIMD | 다수의 독립 CU와 PU가 서로 다른 프로그램과 데이터를 비동기 병렬 처리 |
| 하이브리드 계층 | 노드 간 MIMD(클러스터)와 노드 내 SIMD(GPU)를 결합한 복합 병렬 구성 |

#### 한줄 요약
- 현대 컴퓨팅 시스템은 단일 범주에 고정되지 않고 노드 간 MIMD와 코어 내 SIMD가 결합된 다계층 하이브리드 구조를 갖는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분석 경계(Analysis Boundary)**: 코어 레벨, 소켓 레벨, 클러스터 레벨 등 병렬 처리 분류를 적용하는 시스템의 관찰 계층 기준.

</details>

```text
분석 대상 선정 (코어·소켓·클러스터)
        │
   독립적으로 명령어를 인출하는 흐름이 몇 개인가?
   ┌────┴─────┐
 하나          여럿
   │             │
한 명령이 몇 개   각 흐름이 서로 다른
데이터를 다루는가? 데이터를 다루는가?
 ┌─┴──┐         ┌──┴───┐
하나   여럿      아니오    예
 │      │        │        │
SISD   SIMD     MISD     MIMD
   └────┬───────┴────┬────┘
        │            │
   다른 계층으로 경계를 옮겨 재판정
```

#### 한줄 요약
- 관찰 대상의 계층(코어/소켓/노드)에 따라 명령어 스트림과 데이터 스트림의 수를 순차 판정하여 병렬 아키텍처를 분류한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MISD(Multiple Instruction, Single Data)**: 동일한 데이터 스트림에 대해 여러 독립 연산기가 서로 다른 명령어를 병렬 적용하는 구조.

</details>

| 병렬 처리 아키텍처 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 적용 기준 | 단순 제어 및 엄격한 순차적 프로그램 | 대규모 행렬·벡터·그래픽스·AI 연산 | 결함 허용(우주항공) 및 파이프라인 | 범용 멀티태스킹 OS 및 분산 컴퓨팅 |
| 핵심 특징 | 단일 CU-단일 PU의 순차 실행 | 단일 명령으로 다수 데이터 레인 처리 | 단일 데이터에 여러 명령 스트림 적용 | 독립 프로세서의 비동기 프로그램 실행 |
| 한계 | 클록 주파수 한계(전력 장벽)로 성능 포화 | 조건 분기문(Branch Divergence) 시 비효율 | 하드웨어 구현이 극히 드물고 상용성 미흡 | 동기화 오버헤드 및 프로그래밍 복잡성 |

#### 한줄 요약
- 데이터 병렬 처리에는 SIMD, 독립적 다중 태스크 처리에는 MIMD가 주류 아키텍처로 사용된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: 단일 명령어 제어 하에 다수의 독립 스레드를 대규모 병렬 레인에서 동시 실행하는 GPU 하드웨어 실행 모델.
- **분기 발산(Branch Divergence)**: 동일한 워프(Warp) 내 스레드들이 조건문 분기 경로를 다르게 선택할 때 직렬화가 발생하여 하드웨어 효율이 급락하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **분석 경계** 혼동으로 분류 결과 왜곡 | 프로세서 칩(MIMD)과 코어 내 벡터 유닛(SIMD)의 계층적 분리 | 시스템 전체 병렬 구조의 정확한 파악 |
| **SIMT** 구조에서 조건문 **분기 발산** 발생 | 동일 워프 내 분기 경로 일치화 및 마스킹 제어 | 비활성 레인 발생 방지 및 처리율 극대화 |
| MIMD 멀티스레드 환경의 공유 메모리 경합 | 데이터 파티셔닝 및 락 프리(Lock-Free) 동기화 적용 | 캐시 일관성 트래픽 및 동기화 지연 완화 |
| 대규모 클러스터 노드 간 통신 지연 | 집단 통신 라이브러리 최적화 및 초고속 RDMA 연동 | 노드 간 데이터 교환 오버헤드 최소화 |

#### 한줄 요약
- 실무 병렬 프로그래밍에서는 시스템의 계층별 아키텍처(SIMD/MIMD)에 맞춰 분기 발산과 락 경합을 방지해야 한다.

## Ⅶ. 결론

- 대규모 데이터 병렬성은 **SIMD/GPU**, 독립적 분산 작업은 **MIMD**, 복합 가속 환경은 **계층별 하이브리드 구조**로 설계 및 최적화

#### 한줄 요약
- 플린의 분류를 기반으로 소프트웨어 워크로드의 병렬성 특성을 파악하고 최적의 하드웨어 매핑 전략을 수립해야 한다.
