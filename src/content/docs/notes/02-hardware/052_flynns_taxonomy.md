## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린 분류(Flynn's Taxonomy)**: 마이클 J. 플린(Michael J. Flynn)이 제안한 체계로, 명령어 스트림과 데이터 스트림의 수(단일/다중)에 따라 컴퓨터 구조를 4가지로 분류하는 기법.
- **명령어 스트림(Instruction Stream, IS)**: 제어 유닛(Control Unit)이 생성하여 실행 유닛으로 전달하는 일련의 명령어 시퀀스.
- **데이터 스트림(Data Stream, DS)**: 명령어에 의해 처리되는 피연산자 및 메모리 데이터의 흐름.

</details>

- 정의/개념: 컴퓨터 시스템 내에서 동시에 처리되는 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 개수(단일/다중)를 기준으로 컴퓨터 아키텍처를 4가지로 분류한 체계
- 배경/필요성: 단일 연산 장치 중심의 고전 컴퓨터 구조를 탈피하여, **병렬 처리 시스템의 제어 흐름과 데이터 경로 구조를 체계적으로 분류하고 분석하기 위함**

#### 한줄 요약

- 명령어와 데이터 스트림의 단일 및 다중 조합을 통해 **컴퓨터 구조를 4가지(SISD, SIMD, MISD, MIMD)로 분류합니다.**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **분석 경계(Analysis Boundary)**: 플린 분류를 적용할 때 단일 코어, 단일 소켓 칩, 또는 다중 노드 클러스터 중 어느 계층을 기준으로 평가할지 정하는 범위.

</details>

- 제어 주체 유닛(CU)의 독립성 여부를 판정하는 **명령어 스트림(Single vs Multiple)** 기준 분류
- 동시 연산 처리 대역폭(ALU 레인)을 결정하는 **데이터 스트림(Single vs Multiple)** 교차 평가
- 시스템 계층(코어 vs 칩 vs 노드)에 따른 오해를 방지하기 위한 **분석 경계(Analysis Boundary)** 정의 필수

#### 한줄 요약

- **명령어 스트림 제어(독립 CU), 데이터 스트림 병렬성(ALU 레인), 분석 경계(Boundary) 일관성을 고려합니다.**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **2×2 분류 행렬**: 명령어(S/M)와 데이터(S/M)를 2개의 축으로 결합한 $2 \times 2$ 매트릭스.

</details>

```text
[ Flynn 2x2 분류 행렬 및 스트림 판정 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 분석 타깃 시스템 (코어 / SoC / 클러스터)                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
             ┌─────────────────┴─────────────────┐
             ▼                                   ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ 명령어 스트림 (IS 판정)      │   │ 데이터 스트림 (DS 판정)      │
│  Single (1개 독립 제어기)    │   │  Single (1개 데이터 경로)    │
│  Multiple (다수 독립 제어기) │   │  Multiple (다수 데이터 경로) │
└──────────────┬───────────────┘   └─────────────┬────────────────┘
               │                                 │
               ▼                                 ▼
┌─────────────────────────────────────────────────────────────┐
│ 2x2 분류 행렬 (Flynn's 2x2 Classification Matrix)           │
│  ├─ [Single IS   + Single DS  ] ──> SISD (고전 단일 코어)   │
│  ├─ [Single IS   + Multiple DS] ──> SIMD (벡터 / GPU 코어)  │
│  ├─ [Multiple IS + Single DS  ] ──> MISD (우주항공 중복 검증)│
│  └─ [Multiple IS + Multiple DS] ──> MIMD (멀티코어 / 슈퍼컴)│
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 명령어 스트림(단일/다중), 데이터 스트림(단일/다중) 및 Flynn 2×2 분류 행렬 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 분석 경계 지정 | 논쟁을 방지하기 위해 칩, 코어, 멀티 노드 등 플린 분류를 적용할 시스템 평가 관점을 명확히 확정 |
| 명령 스트림 수 판정 | 확정된 시스템 내에서 제어 유닛이 단일(Single)인지 다중(Multiple)인지 판정 |
| 데이터 스트림 수 판정 | 동일 사이클에 처리되는 데이터 파이프라인이 단일(Single)인지 다중(Multiple)인지 판정 |
| $2 \times 2$ 분류 행렬 매핑 | 산출된 두 가지 기준의 4가지 조합에 따라 최종적으로 해당 컴퓨터 아키텍처의 클래스를 확정 |

#### 한줄 요약

- **분석 경계 지정·명령어 스트림 판정·데이터 스트림 판정·2×2 분류 행렬 매핑** 절차

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Stream Counting**: 시스템 내에서 독립적인 프로그램 카운터(PC) 개수와 동시 활성 데이터 레인 개수를 계측하는 과정.

</details>

```text
[ 플린 분류 판정 파이프라인 ]
                         │
                         ▼
   [ 1. 평가 대상 시스템 분석 경계 확정 (단일 코어 vs 칩 vs 노드) ]
                         │
                         ▼
   [ 2. 독립적인 명령어 제어 유닛(PC) 개수 판정 (Single vs Multiple) ]
                         │
                         ▼
   [ 3. 병렬 처리되는 데이터 스트림(ALU 레인) 개수 판정 (Single vs Multiple) ]
                         │
                         ▼
   [ 4. 2x2 분류 행렬에 대입하여 아키텍처 클래스 도출 ]
                         │
                         ▼
   [ 5. SISD / SIMD / MISD / MIMD 최종 판정 및 혼합 병렬성 명시 ]
```

**동작 원리**

1. **경계 확정**: 분석 관점을 단일 코어 수준인지 다중 소켓 서버 수준인지 명확히 정의
2. **명령어 스트림 판독**: 독립적인 PC(Program Counter)와 디코더가 1개(Single)인지 다수(Multiple)인지 판정
3. **데이터 스트림 판독**: 동일 사이클에 연산되는 피연산자 데이터 레인의 수가 1개인지 다수인지 판정
4. **행렬 대입**: 2개 축의 교차점에 해당하는 클래스(SISD, SIMD, MISD, MIMD) 확정
5. **혼합 아키텍처 분석**: 현대 프로세서의 경우 계층별(노드 레벨 MIMD + 코어 레벨 SIMD) 혼합 병렬성 기술

#### 한줄 요약

- 분석 경계 확정 후 **명령어 스트림(IS) 판독, 데이터 스트림(DS) 판독, 2×2 행렬 교차 매핑을 거쳐 최종 분류를 확정합니다.**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SISD / SIMD / MISD / MIMD**:
  - SISD: 1명령 1데이터, 순차 실행 폰 노이만
  - SIMD: 1명령 다중 데이터, 벡터 연산 및 텐서 코어
  - MISD: 다중 명령 1데이터, 우주항공 다중화 결함 허용
  - MIMD: 다중 명령 다중 데이터, 멀티코어 및 분산 클러스터

</details>

| 2×2 분류 | 명령어 스트림 | 데이터 스트림 | 핵심 아키텍처 특성 | 대표 적용 사례 및 칩 |
|:---|:---|:---|:---|:---|
| **단일 명령 단일 데이터** (SISD) | 단일 (S) | 단일 (S) | 하나의 제어 유닛이 하나의 데이터만 순차적으로 처리하는 고전적인 아키텍처 방식 | 초기 펜티엄 등 단순한 파이프라인 스칼라 CPU 코어 단일 구성 |
| **단일 명령 다중 데이터** (SIMD) | 단일 (S) | 다중 (M) | 하나의 제어 유닛으로 여러 데이터 레인을 동시에 병렬 처리하여 연산 효율을 극대화한 구조 | 인텔 AVX 벡터 확장명령어 및 딥러닝 텐서/행렬 코어 |
| **다중 명령 단일 데이터** (MISD) | 다중 (M) | 단일 (S) | 동일한 데이터를 여러 제어 유닛이 중복 처리하며 교차 검증을 수행하는 결함 허용(Fault-tolerant) 구조 | 단일 에러가 치명적인 우주 항공 및 군사 통신용 중복 시스템 |
| **다중 명령 다중 데이터** (MIMD) | 다중 (M) | 다중 (M) | 다수의 제어 유닛과 데이터 파이프라인이 각각 독립적이고 비동기적으로 연산을 수행하는 구조 | 최신 인텔/AMD 멀티코어 프로세서 및 클러스터 기반 분산 슈퍼컴퓨터 |

#### 한줄 요약

- 고전 순차는 **SISD**, 벡터/텐서는 **SIMD**, 결함 허용은 **MISD**, 멀티코어/분산 환경은 **MIMD**로 분류합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction Multiple Threads)**: 하드웨어는 SIMD 레인이지만 프로그래밍 모델은 개별 스레드로 추상화된 GPU 고유의 실행 모델.
- **계층적 혼합 병렬성**: 노드 간(MIMD: MPI/InfiniBand) + 노드 내(MIMD: OpenMP/Multi-Core) + 코어 내(SIMD: AVX/CUDA)의 3단계 복합 병렬 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템 분석 레이어(코어, 칩 등)에 대한 임의 해석으로 칩 분류의 일관성이 저해되는 문제 | 평가 전 **분석 경계**를 명시하고, 계층별 수용 범위를 엄격하게 고정하여 평가 수행 | **분류 일관성**을 확보하고 객관적인 아키텍처 평가 기준을 확립 |
| 하드웨어 구조(SIMD)와 소프트웨어 실행 모델(SIMT) 간의 혼동 발생 | 소프트웨어 스레드 제어 계층과 물리 연산 레인 계층을 명확히 분리하여 명시 | 하드웨어 아키텍처 관점에서의 정확한 클래스 식별 가능 |
| 최신 AI 칩의 멀티코어와 벡터 코어가 혼재되어 단일 클래스로 분류 불가 | 시스템 계층에 따라 코어 외부(MIMD)와 내부(SIMD)를 결합한 **혼합 병렬성** 표기 적용 | 복합 분산 아키텍처의 다중 계층 특성을 수용하여 기존 분류의 한계 극복 |

#### 한줄 요약

- **분석 경계(코어/칩/노드) 명시, SIMT와 SIMD 개념 분리, 혼합 병렬성(MIMD+SIMD) 복합 표기를 고려해야 합니다.**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **현대 AI 슈퍼컴퓨터 아키텍처 수렴**: 노드 레벨 MIMD(MPI 클러스터) + 소켓 레벨 MIMD(멀티코어 CPU/GPU SM) + 코어 레벨 SIMD(텐서 코어)의 3중 계층 결합.

</details>

- 현대 고성능 컴퓨팅 및 AI 시스템은 **MIMD(멀티코어/멀티노드) 기반에 SIMD/SIMT(벡터/텐서 가속)를 결합한 계층적 혼합 병렬 아키텍처 표준 채택**

#### 한줄 요약

- **명령어 및 데이터 스트림 수와 계층적 분석 경계**에 맞춘 병렬 컴퓨팅 구조 설계가 요구됩니다.
