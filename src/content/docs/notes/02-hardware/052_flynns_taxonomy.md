## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린 분류(Flynn's Taxonomy)**: 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 단일/다중 조합에 따라 컴퓨터 구조를 4가지로 분류한 체계.
- **명령어 스트림(IS)**: 프로세서의 제어 장치에 의해 순차적으로 인출·디코딩되어 실행되는 명령어의 흐름.
- **데이터 스트림(DS)**: 연산 유닛(ALU)에 의해 조작되는 피연산자 및 메모리 데이터의 흐름.

</details>

- 정의/개념: **명령어 스트림(IS)**과 **데이터 스트림(DS)**의 단일·다중 조합으로 컴퓨터 구조를 네 범주로 가르는 **플린 분류(Flynn's Taxonomy)**
- 배경/필요성: 코어 수는 병렬성의 양만 말할 뿐 어떤 종류의 병렬성인지 구분하지 못해, 제어와 데이터를 나누는 별도의 축이 필요

#### 한줄 요약
- 반세기 전 분류가 아직 쓰이는 이유는 하드웨어를 설명해서가 아니라 프로그램이 어떤 병렬성을 가졌는지 묻는 질문이 그대로 유효하기 때문이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 병렬성(Data Parallelism)**: 동일한 명령어를 대규모 데이터 배열에 동시 적용하여 처리 속도를 높이는 병렬성.
- **태스크 병렬성(Task Parallelism)**: 서로 다른 독립된 작업(스레드/프로세스)을 여러 코어에 분산 실행하는 병렬성.

</details>

- 명령어 축과 데이터 축의 2×2 조합으로 병렬 구조를 배타적으로 분류
- **데이터 병렬성(Data Parallelism)**과 **태스크 병렬성(Task Parallelism)**의 경계를 하드웨어 수준에서 규정
- 현대 멀티코어·GPU의 계층적 병렬성을 계층별로 나눠 설명하는 토대 제공

#### 한줄 요약
- 두 병렬성은 배타적이지 않고 층을 이루므로, 현대 시스템에서 이 분류는 배타적 상자가 아니라 계층마다 다시 던지는 질문으로 쓰인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CU(Control Unit)**: 메모리에서 명령어를 인출해 디코딩하는 제어 장치.
- **PU(Processing Unit)**: 산술 논리 연산을 직접 실행하는 연산 처리 장치.

</details>

```text
[플린 분류 2×2]
├─ 단일 명령 (SI)
│  ├─ 단일 데이터 → SISD (단일 코어 CPU)
│  └─ 다중 데이터 → SIMD (벡터 유닛·GPU)
└─ 다중 명령 (MI)
   ├─ 단일 데이터 → MISD (중복 검증 파이프라인)
   └─ 다중 데이터 → MIMD (멀티코어·클러스터)
```

선의 의미: 가지(`├─`)는 명령어 축을 먼저 가른 뒤 데이터 축으로 다시 가르는 순서이며, 잎 노드가 네 범주

| 구성요소 | 책임 |
|:---|:---|
| SISD | **CU(Control Unit)** 하나가 **PU(Processing Unit)** 하나를 제어해 순차 처리 |
| SIMD | 명령어 하나가 다수 데이터 레인에 같은 연산 적용 |
| MISD | 여러 제어 흐름이 같은 데이터에 서로 다른 연산을 중복 적용 |
| MIMD | 독립 제어 흐름들이 각자의 데이터를 비동기로 처리 |
| 하이브리드 계층 | 노드 간 MIMD(클러스터)와 노드 내 SIMD(GPU)를 결합한 복합 병렬 구성 |

#### 한줄 요약
- 네 칸 가운데 MISD만 상용 사례가 희박한데, 같은 데이터에 여러 연산을 겹치는 일이 성능이 아니라 신뢰성을 목적으로 할 때만 값어치를 갖기 때문이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분석 경계(Analysis Boundary)**: 코어 단위, 프로세서 단위, 클러스터 단위 등 병렬성을 판정하는 시스템 계층 범위.

</details>

```text
분석 대상 선정 (코어·소켓·클러스터)
        │
   독립적으로 명령어를 인출하는 흐름이 몇 개인가?
   ┌────┴─────┐
 하나          여럿
   │             │
한 명령이 몇 개   각 흐름이 서로 다른
데이터를 다루는가? 데이터를 다루는가?
 ┌─┴──┐         ┌──┴───┐
하나   여럿      아니오    예
 │      │        │        │
SISD   SIMD     MISD     MIMD
   └────┬───────┴────┬────┘
        │            │
   다른 계층으로 경계를 옮겨 재판정
```

분기 결과: 같은 시스템도 코어 안에서는 SIMD로, 칩 전체로는 MIMD로 판정되므로 분류 결과는 하드웨어가 아니라 어느 경계에서 보았는지가 결정

#### 한줄 요약
- **분석 경계(Analysis Boundary)**를 먼저 못 박지 않으면 같은 장비를 두고 서로 다른 분류가 나오므로, 이 절차에서 실질적인 판단은 첫 단계에서 끝난다.

## Ⅴ. 종류 및 비교

| 병렬 처리 아키텍처 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 적용 기준 | 단순 제어 및 엄격한 순차적 프로그램 | 대규모 행렬·벡터·그래픽스·AI 연산 | 결함 허용(우주항공) 및 파이프라인 | 범용 멀티태스킹 OS 및 분산 컴퓨팅 |
| 핵심 특징 | 단일 CU-단일 PU의 순차 실행 | 단일 명령으로 다수 데이터 레인 처리 | 단일 데이터에 여러 명령 스트림 적용 | 독립 프로세서의 비동기 프로그램 실행 |
| 한계 | 클록 주파수 한계(전력 장벽)로 성능 포화 | 조건 분기문(Branch Divergence) 시 비효율 | 하드웨어 구현이 극히 드물고 상용성 미흡 | 동기화 오버헤드 및 프로그래밍 복잡성 |

#### 한줄 요약
- 네 범주의 한계가 전부 다른 성격이라 성능 순위를 매길 수 없으며, 이 분류는 무엇이 빠른지가 아니라 무엇이 가능한지를 말한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: SIMD 하드웨어 위에서 독립 스레드 프로그래밍 모델을 결합한 GPU 실행 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **분석 경계**를 혼동해 분류 결과가 뒤바뀜 | 칩 레벨(MIMD)과 코어 내 레인(SIMD)으로 계층을 명시적 분리 | 시스템 병렬성 구조의 정확한 파악 |
| **SIMT(Single Instruction, Multiple Threads)** 실행에서 분기 발산 발생 | 같은 실행 묶음의 분기 경로 통일 또는 마스킹 | 비활성 데이터 레인 비율 감소 |
| MIMD 멀티스레드 환경에서 공유 자원 경합 | 데이터 파티셔닝 후 필요 시 락 프리 구조 적용 | 공유 상태와 직렬 임계구역 축소 |
| 대규모 클러스터에서 노드 간 통신 지연 | 집단 통신 최적화와 고속 패브릭 연동 | 노드 간 통신 부담 축소 |

#### 한줄 요약
- 계층을 섞어 보는 순간 잘못된 최적화가 따라 나오므로, 분류의 실무적 값어치는 명칭이 아니라 어느 계층을 손대야 하는지를 가려 주는 데 있다.

## Ⅶ. 결론

- 같은 연산을 대량 데이터에 적용하는 구간은 SIMD로, 독립 태스크는 MIMD로 배치하되, 현대 GPU·클러스터는 단일 범주로 단정하지 말고 코어·노드 계층을 나눠 판단

#### 한줄 요약
- 이 분류가 답하는 것은 하드웨어의 정체가 아니라 내 코드가 어느 축의 병렬성을 갖는가이며, 그 축이 정해져야 비로소 최적화 방향이 하나로 좁혀진다.
