## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린의 분류(Flynn's Taxonomy)**: 마이클 플린(Michael J. Flynn)이 제안한 컴퓨터 아키텍처 분류 체계로, CPU의 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 단일(Single)·다중(Multiple) 조합에 따라 시스템을 4가지 기본 범주로 분류.
- **명령어 스트림(Instruction Stream, IS)**: 프로세서의 제어 장치(Control Unit, CU)에 의해 메모리에서 순차적으로 인출·해독되는 기계어 명령어의 흐름.
- **데이터 스트림(Data Stream, DS)**: 처리 장치(Processing Unit, PU / ALU)에 입력되어 명령어에 의해 조작되는 피연산자 데이터의 흐름.

</details>

- 정의/개념: 컴퓨터 시스템의 병렬성 구조를 **명령어 스트림(IS)과 데이터 스트림(DS)**의 단일(Single)/다중(Multiple) 수량을 기준으로 4대 기본 아키텍처로 분류한 **플린의 분류(Flynn's Taxonomy) 체계**
- 배경/필요성: 다양하게 발전하는 컴퓨터 병렬 처리 시스템의 하드웨어 구조를 **단일 성능 지표만으로는 체계적으로 분류·평가하기 어려운 한계**

#### 한줄 요약
- 플린의 분류는 명령어와 데이터의 흐름 수를 2×2 매트릭스로 조합하여 SISD, SIMD, MISD, MIMD로 병렬성을 규정하는 고전 표준 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 병렬성(Data Parallelism)**: 단일 연산 명령어를 대규모 배열이나 행렬의 개별 데이터 요소들에 동시에 적용하는 병렬 처리 형태.
- **태스크 병렬성(Task Parallelism)**: 서로 다른 독립된 명령어 코드와 제어 흐름(스레드/프로세스)을 다수의 코어에서 동시에 비동기 실행하는 형태.

</details>

- 직관적인 2×2 매트릭스 분류: **SISD, SIMD, MISD, MIMD**의 4개 상호 배타적 영역으로 컴퓨터 시스템의 하드웨어 제어 경계 정의
- 병렬성 유형의 명확화: 단일 명령어로 대량 데이터를 다루는 **데이터 병렬성(SIMD)**과 독립 코어가 협업하는 **태스크 병렬성(MIMD)**의 본질적 차이 규명
- 계층적 하이브리드 확장성: 현대 슈퍼컴퓨터 및 GPU 서버의 **노드 간 MIMD + 노드 내 SIMT/SIMD** 복합 아키텍처 분석의 이론적 토대 제공

#### 한줄 요약
- 2×2 매트릭스로 제어와 데이터의 병렬 구조를 명확히 정의하며, 현대 하이브리드 시스템 분석의 기반이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **제어 장치(Control Unit, CU)**: 메모리로부터 명령어를 인출(Fetch)하고 해독(Decode)하여 처리 장치에 제어 신호를 인가하는 하드웨어 유닛.
- **처리 장치(Processing Unit, PU)**: 제어 장치의 지시에 따라 산술 논리 연산(ALU)을 직접 실행하는 하드웨어 연산 레인.

</details>

```text
[플린의 분류 2×2 매트릭스]
┌─────────────┬─────────────┬─────────────┐
│ 명령어\데이터 │ 단일 데이터  │ 다중 데이터  │
├─────────────┼─────────────┼─────────────┤
│ 단일 명령어  │ SISD        │ SIMD        │
├─────────────┼─────────────┼─────────────┤
│ 다중 명령어  │ MISD        │ MIMD        │
└─────────────┴─────────────┴─────────────┘
```

선의 의미: 행은 명령어 스트림 수, 열은 데이터 스트림 수의 정적 분류 축

| 구성요소 | 책임 |
|:---|:---|
| SISD | 단일 명령어로 단일 데이터의 **순차 처리** |
| SIMD | 단일 명령어로 다중 데이터의 **데이터 병렬 처리** |
| MISD | 다중 명령어로 단일 데이터의 **중복 처리** |
| MIMD | 다중 명령어로 다중 데이터의 **비동기 분산 처리** |

#### 한줄 요약
- 명령어 흐름과 데이터 흐름 두 축만으로 칸을 가르므로 SISD의 제어부를 그대로 두고 연산기만 늘린 것이 SIMD, 제어부까지 복제해 그 비용을 치른 것이 MIMD가 되며, MISD 칸은 같은 데이터를 중복 처리하는 특수 용도로만 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분석 관점(Observation Boundary)**: 코어 레벨, 프로세서 칩 레벨, 랙 클러스터 레벨 등 병렬성을 판정하는 시스템의 관찰 계층 기준.

</details>

```text
분석 대상 하드웨어 계층 경계 설정 (코어 내부, 칩 전체, 클러스터)
                      │
                      ▼
1. 독립된 프로그램 카운터(PC)와 제어 장치(CU) 수 판정
   ┌──────────────────┴──────────────────┐
[ 1개의 제어 장치 (Single IS) ]       [ 복수의 독립 제어 장치 (Multiple IS) ]
   │                                     │
   ▼                                     ▼
2. 1개 명령어가 처리하는 데이터 수는?    2. 각 제어 흐름이 다루는 데이터는?
   ┌──────────┴──────────┐               ┌──────────┴──────────┐
 [ 1개 데이터 ] [ 다중 데이터 ]         [ 동일 데이터 중복 ] [ 독립 데이터 분산 ]
   │              │                       │                    │
   ▼              ▼                       ▼                    ▼
3. SISD 판정   3. SIMD 판정            3. MISD 판정         3. MIMD 판정
   │              │                       │                    │
   └──────────────┴───────────────┬───────┴────────────────────┘
                                  │
                                  ▼
                노드 간 MIMD + 노드 내 SIMD 하이브리드 계층 도출
```

분기 결과: 제어 장치 수에서 갈리면 PC와 제어 회로를 복제하는 비용을, 데이터 레인 수에서 갈리면 연산 레인을 넓히는 비용을 치르며 **4대 기본 영역**이 나뉘고, 현대 시스템은 두 비용을 계층별로 나눠 부담해 **계층적 하이브리드**로 귀결됨

#### 한줄 요약
- 같은 하드웨어라도 코어 내부와 칩 전체, 클러스터 중 어느 경계를 관찰하느냐에 따라 판정이 달라지므로, 분류명을 대기 전에 그 분류가 전제한 관찰 계층을 먼저 밝혀야 한다.

## Ⅴ. 종류 및 비교

| 분류 항목 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 제어 복잡도 | 최저 (단일 파이프라인) | 낮음 (단일 디코더 공유) | 높음 (다중 제어 동기화) | **독립 제어** (최고) |
| 하드웨어 효율성 | 낮음 (병렬성 부재) | **연산기 집적** 극대화 | 낮음 (중복 연산 오버헤드) | 중간 (제어 회로 중복 면적) |
| 프로그래밍 난이도 | **순차 코드** (최저) | 중간 (데이터 벡터화) | 높음 (특수 알고리즘) | **스레드 동기화** (최고) |
| 주력 워크로드 | 단순 순차 로직, 임베디드 | **행렬 곱셈, AI 딥러닝** | 우주항공 결함 허용 | **웹 서버, 가상화 클라우드** |

#### 한줄 요약
- 정형 대량 데이터 연산에는 SIMD가, 독립 멀티태스킹과 분산 환경에는 MIMD가 최적의 아키텍처이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: SIMD의 데이터 레인 구조 위에 스레드 단위의 프로그래밍 추상화와 하드웨어 워프 스케줄링을 결합한 확장 모델.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 시스템 관찰 계층(코어 vs 칩) 혼동으로 인한 아키텍처 분석 오류 | **계층적 분석** 체계 적용 (SoC 수준 MIMD + 코어 내 SIMD) | 시스템 병렬 구조의 정확한 파악 및 최적화 |
| SIMD/SIMT 구조에서 if-else 조건문으로 인한 성능 급락 | **브랜치 프리 마스킹** 알고리즘 적용 | 연산 레인 유휴 제거 및 처리량 극대화 |
| MIMD 환경에서 코어 수 증가에 따른 캐시 일관성 및 락 병목 | **디렉터리 기반 일관성** 및 **락-프리 큐** 적용 | 코어 확장 시 선형적 처리 성능 확보 |

#### 한줄 요약
- 실무에서는 계층적 하이브리드 관점으로 시스템을 분석하고, SIMD의 분기 발산과 MIMD의 락 경합을 방지해야 한다.

## Ⅶ. 결론

- 컴퓨터 아키텍처 병렬성의 기초를 확립한 **고전적 기본 분류 체계(SISD/SIMD/MISD/MIMD)**이며, 현대의 고성능 컴퓨팅 및 AI 시스템은 단일 범주에 머무르지 않고 **클러스터/노드 레벨의 MIMD와 코어/가속기 레벨의 SIMD/SIMT가 유기적으로 결합된 다층 하이브리드 병렬 구조**로 발전

#### 한줄 요약
- 플린의 분류는 컴퓨터 병렬성을 규정하는 영원한 나침반이며, 현대 시스템은 MIMD와 SIMD의 계층적 융합으로 진화했다.
