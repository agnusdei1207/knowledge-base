## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플린 분류(Flynn's Taxonomy)**: 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 단일/다중 조합에 따라 컴퓨터 구조를 4가지로 분류한 체계.
- **명령어 스트림(IS)**: 프로세서의 제어 장치에 의해 순차적으로 인출·디코딩되어 실행되는 명령어의 흐름.
- **데이터 스트림(DS)**: 연산 유닛(ALU)에 의해 조작되는 피연산자 및 메모리 데이터의 흐름.

</details>

- 정의/개념: 명령어 스트림과 데이터 스트림의 개수 조합에 따라 컴퓨터를 **SISD, SIMD, MISD, MIMD**로 분류하는 아키텍처 체계
- 배경/필요성: 병렬 시스템은 코어 수만으로 실행 구조를 설명할 수 없어 명령 제어와 데이터 병렬성을 분리할 분류 축 필요

#### 한줄 요약
- 명령어 흐름(단일/다중)과 데이터 흐름(단일/다중)의 조합으로 컴퓨터의 병렬 처리 방식을 네 가지로 나눈다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 병렬성(Data Parallelism)**: 동일한 명령어를 대규모 데이터 배열에 동시 적용하여 처리 속도를 높이는 병렬성.
- **태스크 병렬성(Task Parallelism)**: 서로 다른 독립된 작업(스레드/프로세스)을 여러 코어에 분산 실행하는 병렬성.

</details>

- **2×2 매트릭스(명령어 축 × 데이터 축)** 기반 병렬 구조 분류
- **데이터 병렬성(SIMD)** 과 **태스크 병렬성(MIMD)** 의 구조적 경계 규정
- 현대 멀티코어 및 GPU의 **계층적 하이브리드 병렬성**을 분석하는 기본 토대 제공

#### 한줄 요약
- 단일·다중 명령어와 데이터 스트림을 교차해 기본 실행 구조를 구분한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CU(Control Unit)**: 메모리에서 명령어를 인출해 디코딩하는 제어 장치.
- **PU(Processing Unit)**: 산술 논리 연산을 직접 실행하는 연산 처리 장치.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 플린의 2x2 컴퓨터 아키텍처 분류 매트릭스                     │
│                                                             │
│                [ 단일 데이터 (SD) ]      [ 다중 데이터 (MD) ]│
│  ┌───────────┬─────────────────────────┬───────────────────┐│
│  │ 단일 명령 │ SISD                    │ SIMD              ││
│  │ (SI)      │ (단일 코어 CPU)          │ (벡터 유닛)       ││
│  ├───────────┼─────────────────────────┼───────────────────┤│
│  │ 다중 명령 │ MISD                    │ MIMD              ││
│  │ (MI)      │ (파이프라인 비행 제어 등)│ (멀티코어/클러스터)││
│  └───────────┴─────────────────────────┴───────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 세로 명령어 스트림 축과 가로 데이터 스트림 축의 단일·다중 조합

| 구성요소 | 책임 |
|:---|:---|
| SISD (Single Inst, Single Data) | 1개의 CU가 1개의 PU를 제어해 단일 명령어-단일 데이터 순차 처리 |
| SIMD (Single Inst, Multiple Data) | 하나의 명령어가 다수 데이터 레인에 같은 연산 적용 |
| MISD (Multiple Inst, Single Data) | 다수의 독립 CU가 단일 데이터 스트림에 각기 다른 명령어를 순차/중복 적용 |
| MIMD (Multiple Inst, Multiple Data) | 다수의 독립 CU와 PU가 각자 서로 다른 명령어와 데이터를 비동기 병렬 실행 |
| 하이브리드 계층 | 노드 간 MIMD(클러스터)와 노드 내 SIMD(GPU)를 결합한 복합 병렬 구성 |

#### 한줄 요약
- 순차 제어의 SISD, 데이터 병렬의 SIMD, 특수 중복의 MISD, 다중 스레드의 MIMD가 핵심 구조를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분석 경계(Analysis Boundary)**: 코어 단위, 프로세서 단위, 클러스터 단위 등 병렬성을 판정하는 시스템 계층 범위.

</details>

```text
컴퓨터 아키텍처 분석 대상 선정 (코어/소켓/클러스터)
      │
      ▼
1. 분석 경계 설정
      │
      ▼
2. 명령어 스트림 판별
      │
      ▼
3. 데이터 스트림 판별
      │
      ▼
4. 아키텍처 분류 확정
      │
      ▼
5. 계층 복합 구조 도출
```

**동작 원리**

1. **분석 경계 설정**: 평가 대상이 단일 코어인지, 소켓인지, 데이터센터 클러스터인지 시스템 범위 특정
2. **명령어 스트림 판별**: 독립적으로 명령어를 인출하고 디코딩하는 프로그램 카운터(PC) 개수 조사
3. **데이터 스트림 판별**: 하나의 명령어로 처리되는 레지스터/메모리 피연산자 데이터 레인의 수 측정
4. **아키텍처 분류 확정**: 2x2 조합 규칙에 따라 기본 플린 범주 확정
5. **계층 복합 구조 도출**: 현대 하이브리드 시스템의 계층별(MIMD+SIMD) 병렬성 통합 평가

#### 한줄 요약
- 시스템 경계 설정 → 제어 흐름 판별 → 데이터 흐름 판별 → 2x2 매트릭스 확정 → 계층 분석 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 병렬 처리 아키텍처 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 적용 기준 | 단순 제어 및 엄격한 순차적 프로그램 | 대규모 행렬·벡터·그래픽스·AI 연산 | 결함 허용(우주항공) 및 파이프라인 | 범용 멀티태스킹 OS 및 분산 컴퓨팅 |
| 핵심 특징 | 단일 CU-단일 PU의 순차 실행 | 단일 명령으로 다수 데이터 레인 처리 | 단일 데이터에 여러 명령 스트림 적용 | 독립 프로세서의 비동기 프로그램 실행 |
| 한계 | 클록 주파수 한계(전력 장벽)로 성능 포화 | 조건 분기문(Branch Divergence) 시 비효율 | 하드웨어 구현이 극히 드물고 상용성 미흡 | 동기화 오버헤드 및 프로그래밍 복잡성 |

#### 한줄 요약
- 순차 처리는 SISD, 대량 텐서는 SIMD, 중복 검증은 MISD, 범용 다중 작업은 MIMD가 최적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: SIMD 하드웨어 위에서 독립 스레드 프로그래밍 모델을 결합한 GPU 실행 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 분석 계층 혼동으로 인한 **아키텍처 분류 오류** | 칩 레벨(MIMD)과 코어 내 레인(SIMD)으로 계층을 명시적 분리 | 시스템 병렬성 구조의 정확한 파악 |
| SIMD/SIMT 연산 시 **분기 발산** 발생 | 같은 실행 묶음의 분기 경로를 통일하거나 마스킹 적용 | 비활성 데이터 레인 비율 감소 |
| MIMD 멀티스레드 환경의 **락 경합** | 데이터 파티셔닝 후 필요 시 락 프리 구조 적용 | 공유 상태와 직렬 임계구역 축소 |
| 대규모 클러스터(MIMD) 분산 통신 지연 발생 | **MPI 집단 통신 최적화** 및 고속 InfiniBand 패브릭 연동 | 노드 간 통신 오버헤드 최소화 |

#### 한줄 요약
- 계층을 분리해 분류하고, 분기 발산을 제거하며, 락 프리 알고리즘과 인피니밴드로 동기화를 최적화한다.

## Ⅶ. 결론

- 동일 연산의 정형 데이터 병렬은 **SIMD**, 독립 태스크는 **MIMD** 구조로 설계
- 현대 GPU·클러스터는 단일 범주로 단정하지 않고 코어·노드별 계층을 분리해 판단

#### 한줄 요약
- 플린 분류를 기반으로 시스템의 계층별 제어 흐름과 데이터 흐름을 명확히 분석하여 최적의 병렬 소프트웨어를 설계해야 한다.
