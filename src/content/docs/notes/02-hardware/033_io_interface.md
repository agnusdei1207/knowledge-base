## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로그램 I/O(Programmed I/O, Polling)**: CPU가 주변 장치의 상태 레지스터를 주기적으로 직접 읽어 준비 완료 여부를 확인하고 워드 단위로 데이터를 복사하는 방식.
- **인터럽트 구동 I/O(Interrupt-Driven I/O)**: 주변 장치가 입출력 준비를 마치면 CPU에 하드웨어 인터럽트(IRQ)를 발생시켜 ISR을 통해 데이터를 전송하는 방식.
- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 DMA 제어기가 주변장치와 주기억장치 간에 블록 단위 데이터를 직접 전송하는 방식.
- **채널 I/O(Channel I/O)**: 자체 명령어 세트를 갖춘 독립 프로세서(I/O 채널)가 복합 I/O 채널 프로그램을 전담 실행하는 고성능 입출력 서브시스템.

</details>

- 정의/개념: 주변 장치와 메인 메모리 간의 데이터 전송 시 CPU 개입 정도와 제어 주체를 분리하여 시스템 처리 효율을 최적화하는 **입출력 제어 체계**
- 배경/필요성: 저속 I/O 장치와의 직접 통신에 따른 CPU 연산 자원 낭비(Busy Waiting) 제거 및 대용량 데이터 전송 시 파이프라인 정체 해소

#### 한줄 요약
- I/O 제어 방식은 CPU를 단순 입출력 루프에서 해방시켜 연산 본연의 임무에 전념할 수 있도록 점진적으로 하드웨어 자율성을 확대한 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바이트 스틸링(Cycle/Byte Stealing)**: DMA 제어기가 CPU의 메모리 버스 유휴 사이클을 1바이트/워드 단위로 가로채어 전송하는 방식.
- **버스트 모드(Burst Mode)**: DMA 제어기가 시스템 버스 제어권을 연속 점유하여 대용량 블록 데이터를 고속으로 일괄 전송하는 방식.
- **인터럽트 벡터(Interrupt Vector)**: 인터럽트를 발생시킨 장치가 자신을 식별하고 대응하는 ISR의 시작 주소를 CPU에 통지하는 고유 번호.

</details>

- 폴링, 인터럽트, DMA, 채널 I/O로 진화하며 **CPU 전송 개입 오버헤드**의 단계적 축소 달성
- 소량 제어 신호는 인터럽트로 즉각 처리하고, 대용량 블록 전송은 **DMA 버스트 및 사이클 스틸링**으로 분담
- 전용 명령 세트(CCW)를 갖춘 독립 **채널 I/O 프로세서**를 통해 CPU와 I/O 서브시스템의 완전 병렬 실행 보장

#### 한줄 요약
- 제어 방식이 고도화될수록 CPU의 전송 개입은 줄어들고, 하드웨어 전용 제어기가 데이터 전송을 전담한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **I/O 컨트롤러(I/O Controller)**: 주변 장치 내부의 상태, 제어, 데이터 레지스터를 관리하며 시스템 버스를 인터페이스하는 하드웨어.
- **DMA 제어기(DMA Controller, DMAC)**: 주소 레지스터, 카운트 레지스터, 버스 중재 회로를 내장하여 직접 전송을 수행하는 전용 제어기.
- **채널 제어기(Channel Controller)**: 채널 명령 워드(CCW)를 메모리에서 직접 인출하여 해독 및 입출력을 독자 수행하는 I/O 전용 프로세서.
- **채널 명령 워드(Channel Command Word, CCW)**: 채널 프로세서가 실행할 읽기, 쓰기, 제어 명령과 데이터 주소 및 바이트 수를 정의한 전용 명령어.

</details>

```text
+-------------------------------------------------------------+
|                호스트 프로세서 (CPU Core & Cache)            |
+-------------------------------------------------------------+
         |                                           ^
         | 1. 입출력 명령 및 초기화 (SIO)            | 5. 전송 완료 인터럽트 (IRQ)
         v                                           |
+-------------------------------------------------------------+
|                   시스템 공유 버스 (System Bus)             |
+-------------------------------------------------------------+
         |                                           ^
         | 2. 버스 마스터 권한 획득                  | 4. 직접 메모리 전송
         v                                           v
+-----------------------------+   +---------------------------+
|    DMA / 채널 제어기 (DMAC) |   |    주기억장치 (DRAM Main) |
| - 주소 및 카운트 레지스터   |   | - OS 버퍼 & DMA 전용 링   |
+-----------------------------+   +---------------------------+
         |                                           ^
         | 3. 장치 제어 및 로컬 버퍼 입출력         |
         v                                           v
+-------------------------------------------------------------+
|               주변 장치 인터페이스 (I/O Controller)         |
| - 상태 / 제어 레지스터    - 데이터 레지스터 / FIFO          |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표는 CPU의 I/O 개시 명령, DMAC의 버스 마스터 점유, 메모리-장치 간 직접 블록 전송, 완료 통지 인터럽트 신호의 상호작용 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU | I/O 전송 시작을 위한 **파라미터 초기화** 및 완료 인터럽트 최종 수신 |
| DMA 제어기 (DMAC) | CPU 개입 없이 버스 제어권을 획득하여 **메모리-장치 간 직접 블록 전송** 수행 |
| I/O 채널 프로세서 | 메모리 상의 **CCW 프로그램**을 독자적으로 인출·해독하여 복합 I/O 일괄 처리 |
| 장치 컨트롤러 | 입출력 장치와 버스 간의 전기 신호 정합 및 내부 **FIFO 버퍼링** 전담 |

#### 한줄 요약
- I/O 제어 시스템은 장치 컨트롤러, DMAC 제어기, I/O 채널 프로세서 및 레지스터 군이 계층적으로 발전한 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **문맥 교환(Context Switching)**: 인터럽트 발생 시 현재 실행 중인 프로세스의 레지스터 상태를 PCB/스택에 저장하고 ISR로 실행 흐름을 전환하는 절차.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 이를 처리하기 위해 실행되는 커널 내 전용 인터럽트 핸들러 함수.

</details>

```text
+-------------------------------------------------------------+
|               입출력(I/O) 데이터 전송 요구 발생             |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     1. 전송 규모 및 특성 판정 |
               +-------------------------------+
                      |                 |
             [소량/비동기 이벤트]       | [대용량 블록 데이터]
                      |                 v
                      | +-------------------------------+
                      | | 2. CPU가 DMAC 레지스터 설정   |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 3. DMAC 버스 제어권 획득(요청)|
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 4. DRAM-장치 간 블록 직접 전송|
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 인터럽트 기반 워드 전송|               |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
|       5. 전송 완료 시 CPU 인터럽트 통지 및 자원 해제         |
+-------------------------------------------------------------+
```

분기 결과: **소량 비동기 이벤트**는 인터럽트로 즉시 처리하여 반응성을 확보하나, **대용량 블록 전송**은 DMA 제어기로 위임하여 CPU 비지 웨이팅 및 사이클 낭비를 제거함

**동작 원리**

1. **전송 규모 판정**: 운영체제 I/O 스케줄러가 전송할 데이터 크기를 분석하여 워드 단위 인터럽트 구동 방식과 DMA 직접 전송 방식 선별
2. **DMAC 레지스터 구성**: 대용량 전송 시 CPU가 DMA 제어기에 메모리 시작 주소, 전송 바이트 수, 전송 방향 레지스터 설정
3. **버스 제어권 중재 및 획득**: DMAC가 버스 중재기에 버스 홀드 신호를 보내고, CPU로부터 승인을 받아 버스 마스터 권한 획득
4. **블록 직접 메모리 전송**: CPU 개입 없이 DMAC가 시스템 버스를 구동하여 장치 FIFO와 메인 메모리 간에 바이트/워드 고속 직접 전송
5. **완료 인터럽트 통지**: 지정된 카운트의 전송이 0에 도달하면 DMAC가 버스 제어권을 CPU에 반납하고 전송 완료 인터럽트(IRQ) 1회 발행

#### 한줄 요약
- 데이터 특성에 따라 소량은 폴링/인터럽트로, 대용량은 DMA로, 다중 장치 복합 제어는 채널 I/O로 분기하여 처리한다.

## Ⅴ. 종류 및 비교

| 제어 방식 | 프로그램 I/O (폴링) | 인터럽트 구동 I/O | DMA (Direct Memory Access) | 채널 I/O (Channel I/O) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초저지연 상태 감시 및 단순 센서 MCU 환경 | 산발적 키보드·직렬 통신 등 비동기 저속 이벤트 발생 시 | SSD·기가비트 NIC 등 고속 대용량 블록 전송 시 | 메인프레임 등 복합 다중 I/O 일괄 처리 환경 |
| 핵심 특징 | CPU **소프트웨어 루프**로 장치 상태를 반복 확인하며 워드 전송 | 하드웨어 인터럽트(**IRQ**) 발생 시 ISR에서 워드 단위 전송 | 전용 **DMAC**가 버스를 제어하여 메모리-장치 간 블록 직접 전송 | 전용 **CCW 명령어**를 해독하는 독립 프로세서 기반 자율 전송 |
| 한계 | 상시 **비지 웨이팅**으로 인한 CPU 연산 자원 낭비 극심 | 고속 I/O 시 잦은 문맥 교환으로 **인터럽트 폭주(Livelock)** 유발 | CPU **캐시 불일치** 발생 및 버스 경합에 따른 메모리 지연 | 채널 제어기 탑재에 따른 **하드웨어 복잡도 및 비용 급증** |

#### 한줄 요약
- 소량 제어에는 폴링/인터럽트가, 고속 대용량 전송에는 DMA가, 대규모 엔터프라이즈 서버에는 채널 I/O가 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DMA 캐시 불일치(DMA Cache Inconsistency)**: CPU 캐시에 저장된 데이터와 DMA가 메인 메모리에 직접 쓴 데이터가 서로 달라지는 문제.
- **인터럽트 완화(Interrupt Moderation / Coalescing)**: 고속 네트워크 수신 시 패킷마다 인터럽트를 걸지 않고 일정 시간이나 패킷 수 단위로 묶어 처리하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고속 패킷 수신 시 인터럽트 폭주(Livelock) | **인터럽트 완화** 및 NAPI 하이브리드 폴링 | CPU 문맥 교환 오버헤드 급감 및 처리량 극대화 |
| DMA 전송 후 CPU 캐시와 메모리 불일치 | 하드웨어 **캐시 스누핑** 및 DMA 버퍼 무효화 | 캐시 일관성 보장 및 데이터 무결성 확보 |
| DMA 버스트 전송으로 인한 메모리 접근 기아 | **사이클 스틸링** 및 버스트 길이 제한 | 연산 파이프라인 정체 방지 및 버스 공정성 유지 |

#### 한줄 요약
- 실무에서는 하이브리드 폴링으로 인터럽트 폭주를 막고, 캐시 무효화로 DMA 일관성을 유지하며, 사이클 스틸링으로 버스 기아를 방지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **RDMA(Remote Direct Memory Access)**: CPU 개입 없이 네트워크 패브릭을 통해 원격 노드의 메모리에 직접 읽기/쓰기를 수행하는 초저지연 전송 기술.
- **NAPI(New API)**: 리눅스 커널에서 패킷 부하가 급증할 때 인터럽트 구동 방식에서 폴링 방식으로 자동 전환하여 인터럽트 폭주를 방어하는 하이브리드 I/O 구조.

</details>

CPU 연산 부하를 최소화하면서 대용량 데이터를 고속 전송하기 위한 하드웨어 중심의 자율적 제어 진화이며, 향후 RDMA 및 CXL 기반의 초저지연 패브릭 통신으로의 통합 발전.

#### 한줄 요약
- I/O 제어는 워크로드 규모에 맞추어 인터럽트와 DMA를 최적으로 조합하고 캐시 정합성을 유지하는 것이 핵심이다.
