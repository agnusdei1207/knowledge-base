## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로그램 I/O(Programmed I/O, Polling)**: CPU가 I/O 장치의 상태 레지스터를 주기적으로 직접 읽어 준비 완료 여부를 확인하고 데이터를 전송하는 방식.
- **인터럽트 구동 I/O(Interrupt-Driven I/O)**: I/O 장치가 데이터 전송 준비를 마치면 CPU에 하드웨어 인터럽트 신호를 보내어 처리를 요청하는 방식.
- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 DMA 제어기가 주변장치와 주기억장치 간에 블록 단위 데이터를 직접 전송하는 방식.
- **채널 I/O(Channel I/O)**: 자체 명령어 세트를 갖춘 독립 프로세서(I/O 채널)가 복합 I/O 프로그램을 전담 실행하는 고성능 입출력 제어 구조.

</details>

- 정의/개념: 주변장치와 메모리 간 데이터 전송 시 CPU 개입 정도와 전송 주체를 단계별로 분리한 **I/O 제어 방식**
- 배경/필요성: CPU와 주변장치 간 현격한 속도 차이로 인해, 단순 반복 조회 시 CPU 자원 낭비 및 입출력 병목 유발

#### 한줄 요약
- I/O 제어 방식 발전사는 CPU를 단순 입출력 루프에서 해방시켜 연산 본연의 임무에 집중시키는 과정이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바이트 스틸링(Cycle/Byte Stealing)**: DMA 제어기가 CPU의 메모리 접근 사이클 틈새나 버스 유휴 사이클을 1바이트/워드 단위로 훔쳐 사용하는 전송 방식.
- **버스트 모드(Burst Mode)**: DMA 제어기가 시스템 버스 소유권을 연속으로 독점하여 대용량 블록 데이터를 고속으로 일괄 전송하는 방식.
- **인터럽트 벡터(Interrupt Vector)**: 인터럽트를 발생시킨 장치가 자신을 식별하고 대응하는 ISR의 시작 주소를 CPU에 전달하는 주소 정보.

</details>

- 폴링은 구조가 단순하나 CPU 연산 시간을 지속적으로 점유
- 인터럽트는 비동기 이벤트 대응에 최적이나 빈번한 발생 시 오버헤드 급증
- DMA는 **바이트 스틸링** 및 **버스트 모드** 기반 대용량 블록 전송 시 CPU 부하 최소화
- 채널 I/O는 다중 장치의 독립 제어 프로그램을 병렬 처리하여 대규모 서버 I/O 처리량 극대화

#### 한줄 요약
- 제어 방식이 뒤로 갈수록 CPU 개입이 줄어드는 대신 하드웨어 복잡도와 제어기 비용이 증가하는 상충 관계를 갖는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **I/O 컨트롤러(I/O Controller)**: 주변장치 내부의 상태, 제어, 데이터 레지스터를 관리하며 장치와 시스템 버스를 인터페이스하는 하드웨어.
- **DMA 제어기(DMA Controller, DMAC)**: 전송 소스/목적지 주소 레지스터, 전송 크기 카운터, 버스 중재 회로를 탑재한 직접 전송 전용 제어기.
- **채널 제어기(Channel Controller)**: 채널 명령 워드(CCW)를 메모리에서 직접 인출하여 해독 및 입출력 연산을 독자 수행하는 I/O 전용 프로세서.
- **채널 명령 워드(Channel Command Word, CCW)**: 채널 프로세서가 실행할 읽기, 쓰기, 제어, 분기 명령과 데이터 주소 및 전송 바이트 수를 정의한 명령어.

</details>

```text
[I/O 제어 구조 발전 단계]
├─ 폴링·인터럽트: CPU ── 시스템 버스 ── I/O 컨트롤러 ── 주변장치
├─ DMA 방식:     CPU ── [DMAC] ── 시스템 버스 ── 주기억장치 (직접 블록 전송)
└─ 채널 I/O:     CPU ── [I/O 채널 프로세서] ── 채널 버스 ── 제어장치 ── 주변장치 군
```

선의 의미: 가지(`├─`)는 발전 단계별 구조; DMA와 채널은 CPU를 데이터 전송 경로에서 완전히 배제

| 구성요소 | 책임 |
|:---|:---|
| **I/O 컨트롤러** | 장치 구동 및 상태/데이터 레지스터 접근 중계 |
| **DMA 제어기** | 주소 증감, 바이트 카운팅, 전송 완료 인터럽트 발생 |
| **채널 제어기** | 메모리 상의 **CCW** 순차 실행 및 다중 장치 동시 입출력 제어 |
| 상태/제어 레지스터 | 준비 상태, 에러 플래그, 인터럽트 요청 상태 보관 |

#### 한줄 요약
- DMAC는 하드웨어 주소 카운터이고 채널 제어기는 완전한 I/O CPU라는 점에서 제어 자율성의 수준이 갈린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **문맥 교환(Context Switching)**: 인터럽트 발생 시 현재 실행 중인 프로세스의 레지스터 상태를 PCB/스택에 저장하고 ISR로 실행 흐름을 전환하는 절차.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 이를 처리하기 위해 실행되는 커널 내 전용 인터럽트 핸들러 함수.

</details>

```text
I/O 요청 발생
      │
      ├─ 1. 전송 데이터 크기가 매우 작은가?
      │      ├─ [예] → 대기 지연이 극히 짧은가?
      │      │          ├─ [예] → 폴링 방식 (Busy-Waiting 후 즉시 완료)
      │      │          └─ [아니오] → 인터럽트 구동 I/O (문맥 교환 후 ISR 처리)
      │      │
      │      └─ [아니오] → 2. 복합 제어 및 다중 장치 관리 요구인가?
      │                      ├─ [아니오] → DMA 제어 (블록 단위 직접 전송 후 완료 인터럽트)
      │                      └─ [예] → 채널 I/O (CCW 기반 독립 채널 프로그램 실행)
```

분기 결과: 데이터 크기와 도착 빈도가 전송 제어 방식을 결정하며, 전송량이 클수록 하드웨어 오프로딩(DMA/채널)이 유리

#### 한줄 요약
- 단발성 극소량 데이터는 폴링과 인터럽트가 단순하지만, 대량 블록 전송은 반드시 DMA와 채널로 넘겨야 시스템이 멈추지 않는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **비지 웨이팅(Busy-Waiting)**: CPU가 특정 I/O 상태 플래그가 변경될 때까지 루프를 돌며 상태 레지스터를 계속 검사하는 유휴 대기 상태.

</details>

| I/O 제어 방식 | 폴링 (Programmed I/O) | 인터럽트 구동 I/O | DMA (Direct Memory Access) | 채널 I/O (Channel I/O) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 매우 짧은 지연·전용 루프 환경 | 산발적 비동기 이벤트·소량 데이터 | 대용량 고속 블록 데이터 전송 | 메인프레임·다중 고속 주변장치 |
| 핵심 특징 | CPU가 상태 레지스터 직접 반복 조회 | 장치 준비 완료 시 인터럽트 구동 | CPU 배제한 메모리 직결 블록 전송 | 독자 채널 명령어로 독립 제어 |
| 한계 | **비지 웨이팅** 기반 CPU 연산 낭비 | 잦은 인터럽트 시 **문맥 교환** 오버헤드 | 버스 중재 경합 및 회로 복잡도 | 고가의 전용 프로세서 하드웨어 필요 |

#### 한줄 요약
- 네 방식은 CPU 개입 지점을 상태 확인, 전송 트리거, 데이터 복사, 명령 실행 순으로 한 단계씩 떼어 낸 계열이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DMA 캐시 불일치(DMA Cache Inconsistency)**: CPU 캐시에 저장된 데이터 사본과 DMA 제어기가 메모리에 직접 쓴 최신 데이터가 서로 불일치하는 상태.
- **인터럽트 완화(Interrupt Moderation)**: 고속 패킷 수신 시 패킷마다 인터럽트를 걸지 않고 일정 시간이나 패킷 수 단위로 묶어 처리하는 기술.
- **버스 마스터링(Bus Mastering)**: 주변장치가 CPU 개입 없이 스스로 버스 제어권을 획득하여 메모리와 직접 통신하는 고급 DMA 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DMA 전송 시 **DMA 캐시 불일치** 발생 | 하드웨어 스누핑 버스 또는 캐시 플러시·무효화 | CPU·장치 간 데이터 정합성 보장 |
| 고속 네트워크 인터럽트 폭주(Livelock) | **인터럽트 완화** 및 NAPI 방식 하이브리드 폴링 | CPU 문맥 교환 감소·처리량 유지 |
| 대용량 DMA의 지속적 버스 독점 | **바이트 스틸링** 또는 버스트 길이 제한 스케줄링 | CPU 메모리 접근 기아 현상 방지 |
| 다중 I/O 인터럽트 우선순위 충돌 | 중첩 인터럽트 및 벡터 인터럽트 제어기(APIC) | 실시간 긴급 장치 최우선 응답 |

#### 한줄 요약
- DMA를 도입하면 CPU 부하는 줄어들지만 캐시 일관성과 버스 중재라는 새로운 하드웨어 복잡성을 떠안게 된다.

## Ⅶ. 결론

- 소량 제어·상태 확인은 **인터럽트 구동 I/O**, 대용량 고속 데이터 전송은 **DMA** 활용 기본으로 결합 적용하고, 네트워크 부하 급증 시 적응형 폴링을 결합한 하이브리드 모델 운용

#### 한줄 요약
- 최고의 I/O 성능은 한 가지 방식을 고집하는 것이 아니라, 부하와 데이터 크기에 따라 인터럽트와 DMA를 적응적으로 전환하는 데서 나온다.
