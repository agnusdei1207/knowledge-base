## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **입출력(Input/Output, I/O)**: CPU•메모리•주변장치 사이의 데이터 전달
- **중앙 처리 장치(Central Processing Unit, CPU)**: 프로그램 명령을 실행하는 장치
- **장치 제어기**: 장치 고유 신호를 CPU가 다룰 수 있는 레지스터 상태와 데이터로 변환하는 하드웨어

</details>

- 정의/개념: CPU•메모리•주변장치의 **제어•전송** 을 잇는 체계
- 배경/필요성: 장치 대기와 직접 데이터 복사로 **CPU 처리 시간 소모**

#### 한줄 요약

- 장치 대기•복사를 분리해 **CPU 관여 시간** 절감

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **데이터 경로 분리**: CPU가 명령만 설정하고 전용 엔진이 실제 데이터를 전송하게 하는 구조
- **버퍼**: 속도가 다른 장치 사이에서 데이터를 임시 보관하는 공간
- **핸드셰이크**: 준비•완료 신호로 장치의 전송 시점을 맞추는 방식
- **비동기 완료 통지**: CPU가 다른 일을 하는 동안 I/O를 수행한 뒤 장치가 완료를 알리는 방식

</details>

- CPU의 전송 관여 시간을 줄이는 **데이터 경로 분리**
- 장치 간 속도 차이를 흡수하는 **버퍼•핸드셰이크**
- CPU 연산과 I/O를 중첩하는 **비동기 완료 통지**

#### 한줄 요약

- 버퍼•핸드셰이크와 **비동기 통지** 로 연산•I/O 중첩

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **장치 드라이버**: 운영체제 I/O 요청을 장치 제어기 명령으로 바꾸는 소프트웨어
- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 복사 없이 장치와 메모리 사이를 전송하는 방식
- **DMA 엔진**: DMA 블록 전송을 실행하는 하드웨어
- **채널 프로세서**: 여러 장치의 복합 I/O 명령열을 CPU 대신 실행하는 전용 처리기

</details>

```text
[CPU•드라이버] -- [주기억장치]
       \              /
       [DMA•채널 엔진] -- [장치•제어기]
```

선의 의미: CPU•드라이버가 주기억장치와 전용 엔진을 제어하고 DMA•채널 엔진이 메모리와 장치 제어기에 함께 접하는 정적 I/O 네트워크 관계다.

| 구성요소 | 책임 |
|:---|:---|
| CPU•드라이버 | 전송 설정•**완료 처리** |
| 장치•제어기 | 장치 신호의 **상태•데이터 변환** |
| DMA•채널 엔진 | 블록 전송•**I/O 명령열 실행** |
| 주기억장치 | 데이터•**제어 정보 보관** |

#### 한줄 요약

- CPU가 전송을 설정하면 전용 엔진이 장치와 메모리 사이의 데이터를 옮긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **대기 시간**: 장치가 준비되거나 완료될 때까지 CPU가 기다리는 시간
- **사건 빈도**: 단위 시간에 장치 완료나 상태 변화가 발생하는 횟수
- **전송 크기**: 한 I/O 요청에서 장치와 메모리 사이를 옮기는 데이터 양
- **명령열 복잡도**: 여러 장치 명령과 조건을 연속 실행해야 하는 정도

</details>

```text
                     [I/O 요청 특성]
                            |
                1. 대기•사건•전송량 판정
                 /          |          \
          [짧고 잦은 대기] [드문 사건] [대용량 블록]
                |            |             |
            2. 폴링      3. 인터럽트      4. DMA
                |            |             |
                +------+-----+-------------+
                       |
               [다중 장치•복합 명령열?]
                    /             \
                 [아니요]          [예]
                    |               |
              [선택 방식 실행]  5. 채널 I/O
                    |               |
                    +-------+-------+
                            |
                      [완료 처리]
```

**동작 원리**

- **1. 대기•사건•전송량 판정**: I/O 부하와 CPU 관여 비용 구분
- **2. 폴링**: 짧고 잦은 장치 상태를 CPU가 직접 확인
- **3. 인터럽트**: 불규칙한 사건을 비동기로 통지
- **4. DMA**: 대용량 블록을 장치와 메모리 사이에 전송
- **5. 채널 I/O**: 전용 프로세서가 복합 명령열 실행

#### 한줄 요약

- 요청 특성별 **폴링•인터럽트•DMA•채널 I/O** 선택

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **폴링**: CPU가 장치 상태를 반복 확인하는 완료 처리 방식
- **인터럽트**: 장치가 사건을 CPU에 비동기로 알리는 완료 처리 방식
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 인터럽트 사건을 처리하는 루틴
- **채널 입출력(Channel Input/Output, 채널 I/O)**: 전용 채널 프로세서가 다중 장치의 I/O 명령열을 실행하는 방식

</details>

| I/O 방식 | 폴링 | 인터럽트 | DMA | 채널 I/O |
|:---|:---|:---|:---|:---|
| 적용 기준 | 매우 짧고 잦은 대기 | 불규칙하고 드문 사건 | 대용량 연속 블록 | 다중 장치•복합 명령열 |
| 핵심 특징 | CPU의 **상태 반복 확인** | 장치 알림 후 **ISR 실행** | 전용 엔진의 **블록 직접 전송** | 채널 프로세서의 **명령열 실행** |
| 한계 | 바쁜 대기•**CPU 점유** | 문맥 전환•**인터럽트 폭주** | 버스 경합•**캐시 일관성** | 전용 하드웨어•**명령 복잡도** |

#### 한줄 요약

- 대기•사건•블록•명령열 특성별 **I/O 방식** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **인터럽트 폭주**: 과도한 완료 통지로 CPU가 인터럽트 처리에 묶이는 현상
- **인터럽트 병합**: 여러 완료 통지를 하나로 모으는 완화 기법
- **캐시 clean**: CPU 수정분을 메모리에 반영하는 동작
- **캐시 invalidate**: DMA가 바꾼 메모리의 오래된 캐시 사본을 버리는 동작
- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: 장치 DMA 주소를 변환•격리하는 하드웨어
- **비휘발성 메모리 익스프레스(Non-Volatile Memory Express, NVMe)**: DMA와 완료 큐를 사용하는 저장 인터페이스

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 대기에서 폴링이 CPU를 독점 | 짧은 구간만 폴링하고 이후 **인터럽트 전환** | **CPU 사용률** 절감 |
| 높은 완료율로 인터럽트 폭주 | **인터럽트 병합**•예산과 적응형 폴링 적용 | **문맥 전환** 감소 |
| 비일관 DMA에서 오래된 캐시 데이터 사용 | 전송 방향별 **clean•invalidate** 와 장벽 적용 | **CPU•장치 데이터** 일치 |
| DMA 주소 오류•버스 경합 | **IOMMU 격리** 와 전송 크기•우선순위 조정 | 메모리 보호•대역폭 안정화 |

> 사례: NVMe는 DMA와 완료 큐 폴링•인터럽트 결합

#### 한줄 요약

- NVMe는 DMA와 **폴링•인터럽트** 를 부하별 결합

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **바쁜 대기**: CPU가 장치 상태를 반복 확인하느라 다른 일을 못 하는 대기 방식
- **문맥 전환 비용**: 인터럽트 처리 시 현재 실행 상태를 저장하고 복원하는 데 드는 시간

</details>

- 짧은 대기는 폴링, 드문 사건은 인터럽트, 대용량•복합 명령은 **DMA•채널 I/O** 선택

#### 한줄 요약

- 대기•사건•전송량•명령 복잡도에 따라 방식 선택
