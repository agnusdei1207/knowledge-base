## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프로그램 I/O(Programmed I/O, Polling)**: CPU가 주변 장치의 상태 레지스터를 주기적으로 직접 읽어 준비 완료 여부를 확인하고 워드 단위로 데이터를 복사하는 방식.
- **인터럽트 구동 I/O(Interrupt-Driven I/O)**: 주변 장치가 입출력 준비를 마치면 CPU에 하드웨어 인터럽트(IRQ)를 발생시켜 ISR을 통해 데이터를 전송하는 방식.
- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 전용 DMA 제어기가 주변장치와 주기억장치 간에 블록 단위 데이터를 직접 전송하는 방식.
- **채널 I/O(Channel I/O)**: 자체 명령어 세트를 갖춘 독립 프로세서(I/O 채널)가 복합 I/O 채널 프로그램을 전담 실행하는 고성능 입출력 서브시스템.

</details>

- 정의/개념: 주변 장치와 메인 메모리 간 데이터 전송 시 CPU 개입 정도와 전송 주체를 단계별로 분리하여 효율을 최적화한 **I/O 제어 방식 아키텍처**
- 배경/필요성: CPU 연산 속도와 저속 I/O 장치 간의 속도 차이로 인한 **CPU 비지 웨이팅(Busy-Waiting) 자원 낭비 극복 및 시스템 처리량 극대화**

#### 한줄 요약
- I/O 제어 방식은 CPU를 단순 입출력 루프에서 해방시켜 연산 본연의 임무에 전념할 수 있도록 점진적으로 하드웨어 자율성을 확대한 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **바이트 스틸링(Cycle/Byte Stealing)**: DMA 제어기가 CPU의 메모리 버스 유휴 사이클을 1바이트/워드 단위로 가로채어 전송하는 방식.
- **버스트 모드(Burst Mode)**: DMA 제어기가 시스템 버스 제어권을 연속 점유하여 대용량 블록 데이터를 고속으로 일괄 전송하는 방식.
- **인터럽트 벡터(Interrupt Vector)**: 인터럽트를 발생시킨 장치가 자신을 식별하고 대응하는 ISR의 시작 주소를 CPU에 통지하는 고유 번호.

</details>

- CPU 개입도의 단계적 축소: 폴링(100% 점유) ➔ 인터럽트(워드당 개입) ➔ DMA(블록 시작/종료 시 개입) ➔ 채널(I/O 프로그램 완료 시만 개입)로 CPU 부하 경감
- 전송 규모 및 대역폭 최적화: 소량 비동기 이벤트는 인터럽트로, 대용량 블록 전송은 **바이트 스틸링** 및 **버스트 모드 DMA**로 처리
- 하드웨어 독립 제어: 채널 I/O는 독립 채널 프로세서가 메모리 상의 명령어를 자체 인출/실행하여 다중 장치를 동시 병렬 제어

#### 한줄 요약
- 제어 방식이 고도화될수록 CPU의 전송 개입은 줄어들고, 하드웨어 전용 제어기가 데이터 전송을 전담한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **I/O 컨트롤러(I/O Controller)**: 주변 장치 내부의 상태, 제어, 데이터 레지스터를 관리하며 시스템 버스를 인터페이스하는 하드웨어.
- **DMA 제어기(DMA Controller, DMAC)**: 주소 레지스터, 카운트 레지스터, 버스 중재 회로를 내장하여 직접 전송을 수행하는 전용 제어기.
- **채널 제어기(Channel Controller)**: 채널 명령 워드(CCW)를 메모리에서 직접 인출하여 해독 및 입출력을 독자 수행하는 I/O 전용 프로세서.
- **채널 명령 워드(Channel Command Word, CCW)**: 채널 프로세서가 실행할 읽기, 쓰기, 제어 명령과 데이터 주소 및 바이트 수를 정의한 전용 명령어.

</details>

```text
[I/O 제어 구조의 단계별 계층 발전]
 ├─ [1단계: 폴링 / 인터럽트]
 │   CPU 코어 ── 시스템 버스 (명령/데이터 직접 복사) ── I/O 컨트롤러 ── 주변장치
 │
 ├─ [2단계: DMA 제어 방식]
 │   CPU 코어 ── (전송 설정/완료 인터럽트만)
 │   [DMA 제어기 (DMAC)] ── 시스템 버스 (직접 블록 전송) ── 메인 메모리 (DRAM) ── 주변장치
 │
 └─ [3단계: 채널 I/O 제어 방식]
     CPU 코어 ── (START I/O 명령 발행)
     [I/O 채널 프로세서 (Channel)] ── 채널 버스 (CCW 독립 실행) ── 장치 제어기 ── 다중 I/O 장치군
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 발전 단계별 구성; DMA와 채널은 CPU를 데이터 전송 경로에서 완전히 배제함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **I/O 컨트롤러** | 주변 장치 인터페이스 | 장치 구동, 상태 레지스터 플래그 및 버퍼 데이터 관리 | 1워드 입출력 중계 |
| **DMA 제어기 (DMAC)**| 시스템 버스 상 독립 칩 | 메모리 주소 자동 증감, 바이트 카운팅, **버스 마스터** 구동 | 블록 전송 완료 시 1회 IRQ |
| **I/O 채널 프로세서**| 대규모 서버/메인프레임 | 메모리 상의 **CCW 채널 프로그램**을 독자 인출·해독·실행 | 독립 I/O CPU |
| **상태/제어 레지스터**| 모든 I/O 장치 공통 | 준비 완료(Ready), 바쁨(Busy), 에러 상태 플래그 보관 | CPU/DMAC 판정 기준 |

#### 한줄 요약
- I/O 제어 시스템은 장치 컨트롤러, DMAC 제어기, I/O 채널 프로세서 및 레지스터 군이 계층적으로 발전한 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **문맥 교환(Context Switching)**: 인터럽트 발생 시 현재 실행 중인 프로세스의 레지스터 상태를 PCB/스택에 저장하고 ISR로 실행 흐름을 전환하는 절차.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 이를 처리하기 위해 실행되는 커널 내 전용 인터럽트 핸들러 함수.

</details>

```text
I/O 데이터 전송 요구 발생
          │
          ▼
1. 전송 데이터 규모 및 특성 판정
   ┌──────────────────────┬──────────────────────┬──────────────────────┐
[ 소량 단발성 / 초저지연 ] [ 산발적 비동기 이벤트 ] [ 대용량 블록 전송 ]     [ 대규모 다중 장치 ]
   │                      │                      │                      │
   ▼                      ▼                      ▼                      ▼
2. 폴링 (Polling)       3. 인터럽트 구동 I/O    4. DMA 직접 전송        5. 채널 I/O (Channel)
   ├─ CPU 루프 대기       ├─ 장치 IRQ 발생        ├─ CPU가 DMAC 초기화   ├─ CPU: SIO 명령
   ├─ 준비 시 워드 복사   ├─ 문맥 저장 ➔ ISR     ├─ DMAC가 버스 점유    ├─ 채널이 CCW 순차 실행
   └─ CPU 연산 100% 점유  └─ 워드 단위 데이터 전송 ├─ DRAM 직접 블록 전송 ├─ 다중 장치 동시 입출력
                                                 └─ 전송 완료 시 1회 IRQ └─ 전체 완료 시 1회 IRQ
```

분기 결과: **데이터 크기가 커질수록** CPU 직접 복사를 배제하고 DMA나 채널 I/O로 하드웨어 오프로딩을 수행하여 시스템 효율을 극대화함

#### 한줄 요약
- 데이터 특성에 따라 소량은 폴링/인터럽트로, 대용량은 DMA로, 다중 장치 복합 제어는 채널 I/O로 분기하여 처리한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 프로그램 I/O (폴링) | 인터럽트 구동 I/O | DMA (Direct Memory Access) | 채널 I/O (Channel I/O) |
|:---|:---|:---|:---|:---|
| 전송 주체 | **CPU (소프트웨어 루프)** | **CPU (ISR 핸들러)** | **전용 하드웨어 (DMAC)** | **독립 I/O 프로세서 (Channel)** |
| CPU 개입 시점 | **상시 개입 (비지 웨이팅)** | 데이터 1워드 도착 시마다 | **블록 전송 시작 및 완료 시** | **채널 프로그램 전체 완료 시** |
| 전송 단위 | 워드(Word) 단위 | 워드(Word) 단위 | **블록(Block, 수 KB~수 MB)** | **다중 레코드/파일 블록 군** |
| 하드웨어 복잡도 | 매우 낮음 (추가 회로 없음) | 낮음 (인터럽트 라인/제어기) | 중간 (DMAC, 버스 중재 회로) | **매우 높음 (I/O 전용 CPU 탑재)** |
| 주요 적용 분야 | 단순 센서 MCU, 초저지연 폴링 | 키보드, 마우스, 직렬 통신 | **NVMe SSD, 기가비트 NIC, GPU** | **메인프레임(IBM Z), 대형 엔터프라이즈** |

#### 한줄 요약
- 소량 제어에는 폴링/인터럽트가, 고속 대용량 전송에는 DMA가, 대규모 엔터프라이즈 서버에는 채널 I/O가 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DMA 캐시 불일치(DMA Cache Inconsistency)**: CPU 캐시에 저장된 데이터와 DMA가 메인 메모리에 직접 쓴 데이터가 서로 달라지는 문제.
- **인터럽트 완화(Interrupt Moderation / Coalescing)**: 고속 네트워크 수신 시 패킷마다 인터럽트를 걸지 않고 일정 시간이나 패킷 수 단위로 묶어 처리하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 고속 네트워크 수신 시 초당 수십만 번의 인터럽트로 시스템 마비(Livelock) | **인터럽트 완화(Interrupt Coalescing) 및 NAPI 하이브리드 폴링** | 문맥 교환 오버헤드 80% 절감 및 네트워크 처리량 극대화 |
| DMA가 메모리를 갱신했으나 CPU 캐시에 이전 데이터가 남아있는 불일치 | **하드웨어 캐시 스누핑 버스 또는 명시적 DMA 캐시 플러시/무효화** | CPU-주변장치 간 데이터 정합성 100% 보장 |
| DMA 버스트 전송으로 인한 CPU 메모리 접근 기아 현상 | **사이클 스틸링(Cycle Stealing) 및 버스트 길이 제한 스케줄링** | CPU 연산 파이프라인 지연 방지 |

#### 한줄 요약
- 실무에서는 하이브리드 폴링으로 인터럽트 폭주를 막고, 캐시 무효화로 DMA 일관성을 유지하며, 사이클 스틸링으로 버스 기아를 방지한다.

## Ⅶ. 결론

- 시스템 I/O 처리량과 CPU 연산 효율성을 극대화하기 위해 **소량 비동기 제어에는 벡터 인터럽트를, 고속 대용량 스토리지 및 네트워크 I/O에는 DMA 버스 마스터링 방식을 표준 구축**하고, 고부하 트래픽 환경에서는 **인터럽트 완화 및 NAPI 하이브리드 폴링 기법**을 적용하며, 데이터 정합성을 위해 **IOMMU 및 캐시 일관성 하드웨어**를 융합하는 고성능 I/O 시스템 아키텍처 확립

#### 한줄 요약
- I/O 제어는 워크로드 규모에 맞추어 인터럽트와 DMA를 최적으로 조합하고 캐시 정합성을 유지하는 것이 핵심이다.
