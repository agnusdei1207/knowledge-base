## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **FPGA(Field-Programmable Gate Array)**: 제조 후 비트스트림을 다운로드하여 논리 회로와 연결을 자유롭게 재구성할 수 있는 반도체 소자.
- **비트스트림(Bitstream)**: FPGA의 내부 SRAM에 적재되어 하드웨어 회로망을 형성하는 설정 바이너리 파일.

</details>

- 정의/개념: **비트스트림**을 바꿔 논리 블록과 배선을 재구성함으로써 모델마다 다른 데이터 경로를 만드는 **FPGA** 기반 AI 가속
- 배경/필요성: GPU는 스케줄링과 캐시 때문에 지연이 요청마다 흔들리고, ASIC은 한 번 굳으면 모델이 바뀔 때마다 재설계 비용이 발생

#### 한줄 요약
- FPGA가 파는 것은 속도가 아니라 회로를 바꿀 권리이며, 모델이 자주 바뀌지 않는 곳에서는 그 권리에 지불한 클록 손해만 남는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **HLS(High-Level Synthesis)**: C/C++ 같은 고수준 프로그래밍 언어를 하드웨어 기술 언어(Verilog/VHDL)로 자동 변환하는 합성 기술.
- **결정적 지연(Deterministic Latency)**: 캐시 미스나 스케줄링 변동 없이 하드웨어 파이프라인에 따라 일정하게 보장되는 응답 시간.

</details>

- 비트스트림 교체만으로 내부 회로를 통째로 바꿀 수 있는 재구성 가능성
- FP8·INT4 같은 비표준 비트 폭 연산기를 필요한 만큼만 직접 구현
- 고정 파이프라인으로 실행 경로를 굳혀 **결정적 지연** 확보

#### 한줄 요약
- FPGA의 경쟁력은 평균 처리량이 아니라 지연의 분산이 거의 없다는 점이며, 그래서 GPU보다 느려도 응답 시한이 걸린 곳에서는 이긴다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CLB(Configurable Logic Block)**: LUT와 플립플롭으로 구성되어 임의의 조합 논리와 순차 논리를 구현하는 기본 단위.
- **DSP 슬라이스**: 고속 곱셈 및 누산(MAC)을 전담하도록 하드웨어로 미리 내장된 연산 블록.

</details>

```text
[FPGA 칩]
├─ 재구성 자원
│  ├─ CLB (LUT + 플립플롭)
│  ├─ DSP 슬라이스 (고속 MAC)
│  └─ BRAM·URAM (가중치·활성화 버퍼)
├─ 프로그래머블 스위치 매트릭스 (자원 간 배선)
└─ 고정 하드웨어
   ├─ PCIe 컨트롤러
   ├─ HBM 인터페이스
   └─ 고속 SerDes
```

선의 의미: 가지(`├─`)는 소유 관계이며, 스위치 매트릭스만이 재구성 대상 자원들을 임의 조합으로 이어 줌

| 구성요소 | 책임 |
|:---|:---|
| **CLB** | 활성화 함수·제어 로직·임의 비트 폭 연산기 구현 |
| **DSP 슬라이스** | 합성곱·행렬 곱셈용 고속 MAC 연산 전담 |
| BRAM·URAM | 가중치와 활성화 텐서를 연산기 바로 옆에 보관 |
| 스위치 매트릭스 | 연산 유닛 간 점대점 스트리밍 경로 형성 |
| 고속 I/O 트랜시버 | PCIe 및 네트워크 패킷의 제로 카피 다이렉트 수신 |

#### 한줄 요약
- 유연성의 대가는 스위치 매트릭스가 차지하는 면적과 지연이며, 같은 연산을 ASIC보다 훨씬 낮은 클록으로 돌릴 수밖에 없는 이유가 여기에 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **양자화(Quantization)**: 32비트 실수를 8비트·4비트 정수로 축소하여 정확도 손실을 최소화하면서 연산량을 줄이는 기법.

</details>

```text
AI 모델 정의 (PyTorch·ONNX)
        │
   양자화·프루닝으로 연산량 축소
        │
   회로 기술을 어디서 시작하는가?
   ┌────┴─────┐
HLS로 자동 변환   RTL 직접 작성
   │             │
   └────┬────────┘
        │
   배치·배선 후 타이밍 검증
        │
   목표 주파수에 수렴하는가?
   ┌────┴─────┐
아니오          예
   │             │
파이프라인 단 추가  비트스트림 생성·적재
플로어플랜 조정      │
   │          스트리밍 추론 개시
   └────┬───────┘
        │
   (다시 배치·배선)
```

분기 결과: **HLS**는 개발 기간을 줄이는 대신 생성 회로가 커져 타이밍 수렴이 어려워지므로, 앞단에서 아낀 시간이 뒷단 반복으로 되돌아오는 구조

#### 한줄 요약
- **양자화**를 맨 앞에 두는 이유는 정확도 조정이 아니라 이후 모든 단계의 자원 사용량을 결정하기 때문이며, 여기서 실패하면 뒷단이 아무리 좋아도 회로가 칩에 들어가지 않는다.

## Ⅴ. 종류 및 비교

| AI 연산 프로세서 | FPGA | GPU | ASIC (TPU/NPU) | CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | 모델별 저지연 추론·재구성 | 학습·범용 병렬 처리 | 안정된 대량 고정 모델 | 제어 중심·소규모 추론 |
| 핵심 특징 | 비트스트림 기반 하드웨어 회로 재구성 | 수천 개 코어 기반 대규모 데이터 병렬 | 전용 시스톨릭 어레이 고집적 고효율 | 복잡한 명령어 세트 및 유연한 실행 |
| 한계 | 개발 난이도 높음·상대적 클록 주파수 낮음 | 높은 전력 소모 및 지연시간 변동 | 설계 변경 불가·초기 개발 비용(NRE) 막대 | 병렬 연산 처리 대역폭 한계 |

#### 한줄 요약
- 네 프로세서의 선택은 성능이 아니라 모델이 얼마나 자주 바뀌고 몇 개나 만드는지로 갈리며, 두 값이 정해지면 답은 거의 자동으로 결정된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **타이밍 클로저(Timing Closure)**: 칩 내부 신호 전달 시간이 목표 클록 주기 내에 들어오도록 설계를 최적화하는 과정.
- **부분 재구성(Partial Reconfiguration)**: 시스템을 중단하지 않고 FPGA의 일부 영역만 실시간으로 회로를 바꾸는 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복잡한 AI 모델 수용 시 온칩 BRAM 용량 부족 | 외부 고대역폭 메모리 연동과 텐서 타일링 적용 | 외부 메모리 접근과 대역폭 요구 감소 |
| 라우팅 혼잡으로 인한 **타이밍 클로저** 실패 | 파이프라인 레지스터와 플로어플래닝 적용 | 목표 주파수에서 경로 지연 검증 |
| 모델 변경 시 전체 영역 재구성 지연 | 독립 영역에 **부분 재구성** 적용 | 서비스 중단 범위와 재구성 시간 축소 |
| **비트스트림** 추출로 하드웨어 설계 복제 위협 | 비트스트림 암호화와 인증 부트 적용 | 비인가 구성 적재와 복제 위험 완화 |

#### 한줄 요약
- **부분 재구성**은 재구성 가능성이라는 원래 강점을 운영 중에도 쓰게 만든 기능이며, 이것이 없으면 회로를 바꿀 권리를 정지 시간과 맞바꿔야 한다.

## Ⅶ. 결론

- 모델 변경이 잦고 지연 상한이 중요하면 **FPGA**를 택하고, 학습·범용 병렬 처리는 GPU로 보내며, 모델이 안정되고 양산 규모가 커지는 시점에 ASIC 전환의 효율과 재설계 비용을 재평가

#### 한줄 요약
- FPGA는 GPU와 ASIC 사이의 절충이 아니라 두 축 모두에서 지는 대신 변경 비용에서만 이기는 선택이며, 그 축이 중요하지 않으면 고를 이유가 없다.
