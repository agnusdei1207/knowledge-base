## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마이크로컨트롤러 유닛(Microcontroller Unit, MCU)**: CPU 코어에 램, 플래시, 핀 구멍까지 손톱만 한 칩 하나에 다 때려 박아서, 세탁기나 밥통에 납땜 하나면 끝나는 극강의 가성비 칩이다.
- **마이크로프로세서 유닛(Microprocessor Unit, MPU)**: 머리통(CPU 코어)만 엄청나게 똑똑해서, 램이나 하드를 메인보드에 주렁주렁 달아줘야만 윈도우나 리눅스를 쌩쌩 돌릴 수 있는 고성능 괴물이다.

</details>

- 정의: 하드웨어 온칩(On-chip) 통합도, MMU/OS 요구사항 및 실시간(Real-Time) 제어 목적에 따른 대표적 반도체 2대 분류인 **MCU vs MPU**
- 배경: 밥통이나 세탁기 돌리자고 비싼 윈도우(MPU)를 깔 수는 없고, 반대로 고화질 3D 게임을 돌리는데 램 1MB짜리 싸구려 칩(MCU)을 쓸 수는 없는 극단적인 목적 차이 때문

#### 한줄 요약

- 칩 하나로 다 해 먹는 저전력 제어용이 MCU이고, 부품을 주렁주렁 달아서 고성능 OS를 돌리는 게 MPU이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **온칩(On-Chip)**: CPU, 램, 하드디스크 역할을 하는 부품들을 손톱만 한 실리콘 칩 한 덩어리 안에 무식하게 다 우겨넣은 기술이다.
- **메모리 관리 유닛(Memory Management Unit, MMU)**: 가상 메모리를 만들어서 윈도우나 리눅스가 수십 개의 프로그램을 메모리가 안 꼬이게 띄우도록 해주는 필수 하드웨어 칩이다.
- **실시간 운영체제(Real-Time Operating System, RTOS) 및 베어메탈(Bare-Metal)**: OS 껍데기를 아예 벗어던지고(베어메탈) 0.001초의 딜레이도 없이 모터를 칼같이 제어하는 극단적인 하드 실시간 환경이다.

</details>

- CPU, 램, 하드, 통신 포트까지 손톱만 한 칩 하나에 다 때려 박은 **온칩** 소형화로 배터리 하나로 1년을 버팀 (MCU).
- 머리통만 크고 똑똑해서 외부 램(LPDDR) 확장이 필수이며, **메모리 관리 유닛(MMU)**을 달아 리눅스나 윈도우를 쌩쌩 돌림 (MPU).
- 0.001초라도 늦으면 드론이 땅에 처박히는 하드 실시간 제어(**RTOS/베어메탈**)와, 느려도 여러 창을 동시에 띄우는 멀티태스킹(Rich OS)으로 용도가 갈림.

#### 한줄 요약

- 칩 안에 다 집어넣어 전기를 아끼는 MCU와 외부 메모리를 확장해 무거운 리눅스를 돌리는 MPU의 대결이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **엠씨유 온칩 자원(MCU On-chip Resource)**: 칩 하나에 아득바득 우겨넣은 쥐꼬리만 한 램(SRAM)과 플래시, 그리고 아날로그 핀 제어기들이다.
- **엠피유 외부 자원(MPU External Resource)**: 칩 안에는 공간이 없어서 메인보드에 따로 꽂아 쓰는 기가바이트급 외부 램(DDR)과 고속 버스 확장팩이다.

</details>

```text
[ 제어 몰빵 MCU vs 고성능 확장 MPU 프레임워크 ]

[ MCU 아키텍처 ]
 [ 경량 CPU 코어 ] ── [ MCU 온칩 자원 (초소형 램, 플래시, 핀 센서) ]
 (하나의 칩 안에 전부 다 구겨 넣음)

[ MPU 아키텍처 ]
 [ 고성능 멀티코어 ] ── [ MPU 외부 자원 (거대 DDR 램, NVMe 디스크) ]
 (메인보드에 부품들을 냅다 확장함)
```

| 구성요소 | 책임 |
|:---|:---|
| MCU 제어부 | 밥통 온도 맞추기나 드론 모터 돌리기처럼 1ms의 지연도 용납 못 하는 **하드 실시간** 연산을 묵묵히 수행하는 경량 코어 |
| **엠씨유 온칩 자원** | 칩 하나에 아득바득 우겨넣은 쥐꼬리만 한 램(SRAM)과 플래시, 그리고 아날로그 핀(ADC/PWM) 제어기 |
| MPU 처리부 | 무식하게 코어를 수십 개 때려 박고 **MMU**까지 달아서 리눅스나 윈도우를 띄우는 고성능 멀티코어 괴물 |
| **엠피유 외부 자원** | 칩 안에는 공간이 없어서 메인보드에 따로 꽂아 쓰는 기가바이트급 외부 램(DDR)과 고속 버스(PCIe) 확장 자원 |

#### 한줄 요약

- MCU는 자원을 칩 안에 모조리 때려 박고, MPU는 메인보드에 램과 하드를 거창하게 깔아놓고 코어를 돌린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **하드 실시간 요구(Hard Real-time Demand)**: 정해진 시간(예: 1ms) 안에 계산을 못 끝내면 에러 수준이 아니라 자동차가 들이박고 드론이 처박히는 치명적인 시간 제약이다.

</details>

```text
[ 실시간 억세스 및 운영체제 체급별 처리기 십자포화 흐름 ]
                                 │
                                 ▼
         [ 1. 지연 한계 판정: 1ms라도 늦으면 기계가 작살나는가? (하드 실시간 요구) ]
                                 │
                                 ▼
   [ 2. 운영체제 판독: 윈도우나 리눅스(MMU 필수)가 돌아가는 거창한 시스템인가? ]
                                 │
         ┌───────────────────────┼───────────────────────┐
      ( 실시간 몰빵 )         ( OS/화면 몰빵 )        ( 둘 다 필요함 )
         ▼                       ▼                       ▼
    [ 3. MCU 단독 채택 ]     [ 3. MPU 단독 채택 ]    [ 4. MCU + MPU 하이브리드 ]
         │                       │                       │
         └───────────────────────┴───────────────────────┘
                                 ▼
                        [ 칩셋 및 보드 아키텍처 확정 ]
```

### 동작 원리

1. 지연 한계 판정: 모터 제어처럼 0.001초 늦었다고 드론이 땅에 처박히는 **하드 실시간 요구**가 필수인지 칼같이 잼.
2. 운영체제 체급 판독: 윈도우나 리눅스(**MMU** 필수)가 필요한 고스펙 화면 터치 앱인지 파악함.
3. 칩셋 십자포화 분기: 실시간 제어만 하면 **MCU**, 빵빵한 메모리와 OS가 필요하면 **MPU**로 노선을 갈라버림.
4. 혼합 아키텍처 확정: 드론처럼 실시간 모터 제어(MCU)와 고화질 카메라 전송(MPU)이 둘 다 필요하면 칩을 두 개 꽂아버림.

#### 한줄 요약

- 1ms라도 늦으면 큰일 나는 곳엔 MCU를 박고, 윈도우/리눅스를 돌려야 하면 MPU를 쓴다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **최악 실행 시간(Worst-Case Execution Time, WCET)**: 아무리 꼬이고 딜레이가 걸려도 "이 계산은 죽었다 깨어나도 3밀리초 안에는 무조건 끝난다"라고 보장하는 한계선이다.

</details>

| 비교 항목 | **마이크로컨트롤러** (MCU) | **마이크로프로세서** (MPU) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 세탁기, 전기밥솥, 드론 모터처럼 전원 꽂자마자 1초 만에 켜져서 평생 안 꺼지고 돌아가야 할 시 | 스마트폰, PC, 자율주행 메인 컴퓨터처럼 리눅스/안드로이드 깔고 복잡한 앱을 미친 듯이 띄울 시 |
| 아키텍처 핵심 구현 특징 | 칩 하나에 램, 롬, 포트 다 쑤셔 박아서 보드에 이것만 달랑 하나 납땜하면 끝나는 극강의 가성비 칩 | 머리만 더럽게 커서 메인보드에 기가바이트급 램, 디스크를 줄줄이 달아줘야만 비로소 작동하는 까탈스러운 칩 |
| 극복해야 할 태생적 한계점 | 램이 몇 킬로바이트(KB) 수준이라 변수 몇 개 선언 잘못하면 메모리 터져서 장비가 먹통 됨 | 전기를 무식하게 퍼먹고, 리눅스 특성상 스케줄링 튀면(**지터**) 모터 제어하다 딜레이 먹고 땅에 처박힘 |

#### 한줄 요약

- 배터리로 평생 모터만 돌릴 거면 MCU, 전원 빵빵하게 먹이며 리눅스 돌릴 거면 MPU를 써라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **신호 무결성(Signal Integrity)**: MPU가 밖에 달린 램(DDR)이랑 미친 듯이 데이터를 주고받을 때, 전자파 노이즈 때문에 0이 1로 뒤집히는 끔찍한 사태를 막아내는 회로 설계 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 리눅스 깔린 MPU로 모터 돌렸더니 스케줄링 밀릴 때마다 모터가 덜덜 떨며 지터(Jitter)가 폭발하는 대참사 발발 | 뇌 비우고 모터만 1ms 단위로 칼같이 돌리는 전용 **MCU**를 옆에 하나 더 박아서 제어 전담시킴 | OS가 버벅대든 말든 모터는 한 치의 오차 없이 미친 듯이 돌아가는 극강의 실시간 격리 달성 |
| MPU가 외부 램(DDR)이랑 통신하는데 선로 노이즈 때문에 데이터가 깨지는 **신호 무결성** 파괴 재앙 | 보드 깎을 때 임피던스(저항) 뼈 깎듯 맞추고, 주변에 구리선 떡칠해서 전자파 노이즈(EMI) 강제 차단 | 고속 메모리 뻥튀기해도 버스 에러 한 번 안 나는 철통 방어 회로 구축 완료 |
| MCU에서 램 20KB짜리 쓰면서 재귀 함수 잘못 짰다가 스택 오버플로우 터져서 기계가 뻗어버리는 참사 | 동적 할당(malloc) 따위 얄짤없이 금지하고 변수들 싹 다 정적 메모리에 쑤셔 박는 극한의 스택 다이어트 | 10년을 안 끄고 돌려도 메모리 터질 일 없는 불멸의 임베디드 펌웨어 완성 |

#### 한줄 요약

- MPU의 버벅거림(지터)은 옆에 MCU를 달아서 격리하고, 메모리가 쥐꼬리만 한 MCU에서는 변수 다이어트를 빡세게 해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **처리기 선택 기준(Processor Selection Criteria)**: 이 기계가 0.001초 단위로 모터를 깎는 놈인지, 아니면 화면에 유튜브를 띄워야 하는 놈인지 용도를 따져보고 칩을 박는 돈지랄 잣대이다.

</details>

- **처리기 선택 기준** 원칙에 따라, 센서/액추에이터 실시간 칼각 제어는 **MCU**, 딥러닝/GUI/웹서버 인프라는 **MPU** 채택 기조 확립함

#### 한줄 요약

- 하드 실시간 모터 제어는 닥치고 MCU, 리눅스 돌리고 화면 띄우려면 돈 발라서 MPU를 깔아라.
