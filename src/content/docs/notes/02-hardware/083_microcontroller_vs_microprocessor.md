## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **마이크로컨트롤러(Microcontroller Unit, MCU)**: 처리기•메모리•주변장치를 한 칩에 통합한 제어용 반도체이다.
- **마이크로프로세서(Microprocessor Unit, MPU)**: 외부 메모리•입출력을 확장하는 처리기 중심 반도체이다.

</details>

- 정의/개념: CPU와 메모리•주변장치를 온칩에 통합한 **MCU**와 외부 메모리•I/O 확장을 전제로 하는 MPU의 처리기 구조를 구분한 것이다.
- 배경/필요성: 결정적 저전력 제어와 대용량 메모리 기반 범용 OS는 자원•시간 요구가 달라 하나의 처리기 구성으로 모두 최적화하기 어렵다.

#### 한줄 요약

- MCU는 **제어 자원을 온칩 통합**하고, MPU는 외부 메모리와 I/O를 확장하는 처리기 구조이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **온칩(On-Chip)**: 처리기와 메모리•주변장치가 같은 칩 안에 배치된 상태이다.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소를 변환하고 프로세스 메모리를 격리하는 하드웨어이다.
- **실시간 운영체제(Real-time Operating System, RTOS)**: 태스크의 결정적 스케줄링을 지원하는 운영체제이다.
- **운영체제(Operating System, OS)**: 하드웨어 자원을 관리하고 응용 실행 환경을 제공한다.

</details>

- **MCU 온칩 통합**: 보드•전력•제어 지연 감소한다.
- **MPU 외부 확장•MMU**: 대용량 응용과 프로세스 격리이다.
- **실행 환경 차이**: RTOS•베어메탈의 결정성과 범용 OS의 기능성이다.

#### 한줄 요약

- **결정적 제어•범용 OS 기능**에 따른 MCU•MPU을 구분한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **MCU 제어부(MCU Control Unit)**: 베어메탈이나 RTOS로 결정적 제어를 실행하는 구성이다.
- **MCU 온칩 자원(MCU On-chip Resource)**: 메모리•타이머•변환기•통신 장치를 한 칩에서 제공하는 구성이다.
- **MPU 처리부(MPU Processing Unit)**: MMU와 범용 OS로 복합 응용을 실행하는 구성이다.
- **MPU 외부 자원(MPU External Resource)**: 외부 메모리와 고속 I/O로 용량•기능을 확장하는 구성이다.

</details>

```text
MCU 구조: [MCU 제어부] -- [MCU 온칩 자원]

MPU 구조: [MPU 처리부] -- [MPU 외부 자원]
```

선의 의미: 각 선은 MCU 내부 통합 또는 MPU 외부 확장 관계이며, 두 처리기 구조 사이의 직접 연결은 없다.

| 구성요소 | 책임 |
|:---|:---|
| MCU 제어부 | **결정적 제어 실행** |
| MCU 온칩 자원 | **메모리•주변장치 제공** |
| MPU 처리부 | **범용 OS•응용 실행** |
| MPU 외부 자원 | **메모리•I/O 확장** |

#### 한줄 요약

- **MCU 내부 통합•MPU 외부 확장** 구조를 비교한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **인터럽트(Interrupt)**: 장치 사건이 현재 실행을 잠시 멈추고 처리 루틴을 호출하는 신호이다.
- **텔레메트리(Telemetry)**: 장치의 상태•진단값을 원격 시스템에 전달하는 데이터이다.

</details>

```text
[시스템 시간•기능 요구]
           │
           ▼
1. 하드 실시간 요구 판정
           │
           ▼
2. OS•응용 복잡도 판정
     ┌─────┼──────────┐
     │ 제어 중심      │ 응용 중심     │ 동시 요구
     ▼                ▼               ▼
   [MCU]            [MPU]       [MCU + MPU 분할]
     └─────────┬──────┴───────────────┘
               ▼
3. 메모리•I/O•전력 검증
               │
               ▼
4. 시간•장애 경계 검증
               │
               ▼
         [처리기 구성 확정]
```

**동작 원리**

1. **하드 실시간 요구 판정**: 제어 루프의 데드라인과 허용 지터를 측정하여 결정적 실행 필요성을 확인한다.
2. **OS•응용 복잡도 판정**: MMU, 대용량 메모리, 그래픽과 네트워크 서비스 등 범용 OS 요구를 확인한다.
3. **메모리•I/O•전력 검증**: 필요한 자원이 MCU 온칩 범위에 드는지, MPU 외부 확장과 전력 비용을 감당할 수 있는지 비교한다.
4. **시간•장애 경계 검증**: 혼합 구성에서는 MPU 장애나 부하가 MCU 제어 데드라인과 안전 출력에 영향을 주지 않는지 시험한다.

#### 한줄 요약

- **결정적 제어와 복합 응용 요구**를 각각 평가하여 MCU, MPU 또는 역할을 나눈 혼합 구성을 결정한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **하드 실시간**: 데드라인 위반을 시스템 실패로 보아 허용하지 않는 제어 조건이다.
- **범용 운영체제**: 프로세스•가상 메모리•파일 등 다양한 응용 기능을 제공하는 운영체제이다.

</details>

| 처리기 유형 | 마이크로컨트롤러(MCU) | 마이크로프로세서(MPU) |
|:---|:---|:---|
| 적용 기준 | 센서•모터의 **하드 실시간 제어** | 화면•네트워크의 **대용량 응용** |
| 핵심 특징 | **제어 자원 온칩 통합** | **외부 메모리•I/O 확장** |
| 한계 | **메모리•연산 확장** 제한 | **전력•보드 비용•응답 변동** |

#### 한줄 요약

- **하드 실시간 제어**는 MCU, 대용량 응용은 MPU가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **최악 실행 시간(Worst-case Execution Time, WCET)**: 태스크가 가장 오래 걸리는 경로의 실행 시간 상한이다.
- **지터(Jitter)**: 주기 작업의 실제 시작•완료 시각이 기준 시각에서 흔들리는 정도이다.
- **신호 무결성**: 전기 신호가 왜곡•잡음 없이 수신 조건을 만족하는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| WCET와 인터럽트 지연 합이 주기를 넘어 **데드라인 위반** | **WCET•인터럽트 지연 측정** | **하드 실시간 제어** 보장 |
| 동적 할당과 깊은 호출로 **MCU 메모리 고갈** | **정적 할당•스택 사용량 계측** | **실행 중 메모리 부족** 예방 |
| 범용 OS 스케줄링으로 **MPU 제어 지터** 증가 | **실시간 코어•MCU 제어 분담** | **응답 시간 예측성** 향상 |
| 외부 메모리•I/O 배선 잡음으로 **신호 무결성 저하** | **전원•배선•신호 무결성 검증** | **외부 장치 통신 오류** 감소 |

#### 한줄 요약

- **실시간 코어•MCU 분담**으로 MPU 제어 지터 격리가 핵심이다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **베어메탈(Bare Metal)**: 운영체제 없이 펌웨어가 하드웨어를 직접 제어하는 실행 방식이다.
- **데드라인(Deadline)**: 제어 처리를 끝내야 하는 제한 시각이다.

</details>

- 결정적 제어는 **MCU**, 복합 OS는 **MPU**, 동시 요구는 분할이 핵심이다.

#### 한줄 요약

- 실시간 제어와 대용량 OS의 **시간•메모리 요구가 충돌**하면 MCU와 MPU 사이에 역할과 장애 경계를 분리한다.
