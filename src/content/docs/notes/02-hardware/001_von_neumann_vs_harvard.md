## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 아키텍처(Von Neumann Architecture)**: 명령어와 데이터를 단일 메모리와 단일 버스에서 처리하는 컴퓨터 구조.
- **하버드 아키텍처(Harvard Architecture)**: 명령어 메모리와 데이터 메모리를 물리적으로 분리해 동시 접근을 가능하게 하는 컴퓨터 구조.
- **수정 하버드 아키텍처(Modified Harvard Architecture)**: L1 캐시 수준에서 명령어·데이터 경로를 분리하되 하위 메모리는 공유하는 절충 구조.

</details>

- 정의/개념: 명령어와 데이터의 저장 경로를 공유하거나 분리해 CPU 접근 대역폭을 결정하는 **컴퓨터 메모리 구조**
- 배경/필요성: 명령어 인출과 데이터 접근이 같은 경로를 사용할 때 발생하는 **폰 노이만 병목** 완화

#### 한줄 요약
- 폰 노이만은 한 길을 명령어와 데이터가 함께 쓰고, 하버드는 두 길을 따로 내어 동시에 달릴 수 있게 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **폰 노이만 병목(Von Neumann Bottleneck)**: 명령어와 데이터가 공유 버스의 대역폭을 경쟁해 CPU 처리 속도가 메모리 전송 속도에 제한되는 현상.
- **명령어 인출(Instruction Fetch)**: CPU가 다음에 실행할 명령어를 메모리에서 가져오는 파이프라인 첫 단계.

</details>

- 폰 노이만: 공유 경로의 **폰 노이만 병목**으로 명령어 인출과 데이터 접근이 순차화
- 하버드: 명령어·데이터 전용 경로 분리로 동시 접근 가능해 처리량 향상
- 수정 하버드: L1 I-cache·D-cache 분리로 코어 근방 병목 완화, 하위 통합 메모리로 저장 공간 유연성 보존

#### 한줄 요약
- 공유 구조는 유연하지만 목이 막히고, 분리 구조는 빠르지만 공간 배분이 고정된다는 상충이 수정 하버드로 절충된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache, I-cache)**: 명령어 인출 전용으로 분리된 캐시로, 데이터 접근과 독립적인 명령어 대역폭을 제공.
- **데이터 캐시(Data Cache, D-cache)**: 데이터 읽기·쓰기 전용으로 분리된 캐시로, 명령어 인출과 독립적인 데이터 대역폭을 제공.
- **통합 메모리(Unified Memory)**: 명령어와 데이터가 같은 주소 공간을 공유하는 단일 물리 저장 자원.

</details>

```text
폰 노이만 구조
└─ 통합 메모리 ─── 공유 버스 ─── CPU

하버드 구조
├─ 명령어 메모리 ─── 명령 버스 ─┐
└─ 데이터 메모리 ─── 데이터 버스 ┤── CPU

수정 하버드 구조
├─ I-cache ─┐
├─ D-cache ─┼── CPU
└─ 통합 메모리 (공유)
```

선의 의미: `───`는 버스 연결(전송 경로), 가지(`├─`)는 구성요소 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 통합 메모리 | 명령어·데이터 공동 저장 및 주소 공간 제공 |
| 명령어 메모리 | 실행 코드 독립 저장·**명령어 인출** 전용 대역폭 |
| 데이터 메모리 | 피연산자·결과 독립 저장·데이터 접근 전용 대역폭 |
| I-cache | 명령어 인출 지연 감소·데이터 접근과 경합 차단 |
| D-cache | 데이터 접근 지연 감소·명령어 인출과 경합 차단 |

#### 한줄 요약
- 순수 구조는 저장소부터 나뉘지만, 수정 하버드는 캐시 계층만 나누고 아래 메모리는 합쳐 공간 낭비를 줄인다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 유지보수(Cache Maintenance)**: I-cache·D-cache 간 일관성을 유지하기 위해 캐시 무효화·플러시를 수행하는 작업.
- **자기 수정 코드(Self-Modifying Code)**: 실행 중 데이터 경로로 생성한 명령어를 즉시 실행하는 코드 패턴.

</details>

```text
CPU 명령어 인출 요청
        │
        ├─ 폰 노이만: 통합 메모리 버스 경유 → 인출 (데이터 접근과 직렬화)
        │
        └─ 하버드/수정 하버드: I-cache 경유 → 인출
                                              │
                              데이터 접근은 D-cache 경유로 동시 수행
                                              │
                              1. 캐시 미스 시 통합 메모리 반입 (수정 하버드)
                              2. 자기 수정 코드: D-cache 플러시 → I-cache 무효화
```

**동작 원리**

1. **캐시 미스 시 통합 메모리 반입**: 수정 하버드에서 I-cache·D-cache 미스는 공유 하위 메모리에서 라인 반입
2. **자기 수정 코드**: 데이터 경로로 쓴 명령어를 실행하려면 D-cache 플러시·I-cache 무효화로 일관성 확보

#### 한줄 요약
- 분리 경로의 이점은 동시 접근이지만, 자기 수정 코드가 있으면 두 캐시를 명시적으로 동기화해야 그 이점을 지킬 수 있다.

## Ⅴ. 종류 및 비교

| 구조 유형 | 폰 노이만 | 수정 하버드 | 하버드 |
|:---|:---|:---|:---|
| 적용 기준 | 저장 공간 유연성 우선, 동시 접근 불필요 | 범용 OS와 코어 대역폭을 동시에 요구 | 동시 인출·데이터 접근 필수, 공간 고정 허용 |
| 핵심 특징 | 통합 메모리·공유 버스 | I-cache·D-cache 분리·하위 **통합 메모리** | 물리 분리 메모리·전용 버스로 **최대 대역폭** |
| 한계 | 공유 버스의 **폰 노이만 병목** | 자기 수정 코드 시 캐시 유지보수 필요 | 코드·데이터 공간 고정 배분·갱신 제약 |

#### 한줄 요약
- 저장 공간 유연성이 우선이면 폰 노이만, 동시 접근이 필수면 하버드, 둘 다 필요하면 수정 하버드가 현실적 선택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 주변 장치가 메모리와 직접 데이터를 전송하는 방식으로, 캐시 사본과 메모리 사본의 불일치를 유발할 수 있음.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 버스에서 명령어 인출·데이터 접근 직렬화 | I-cache·D-cache 분리 및 접근 패턴 분석 | 코어 근방 **폰 노이만 병목** 완화 |
| DMA가 D-cache 사본과 다른 메모리 값 갱신 | **캐시 유지보수**·버퍼 소유권 전환 동기화 | 데이터 사본 불일치 방지 |
| 자기 수정 코드 실행 시 I-cache 오래된 명령어 인출 | D-cache 플러시 후 I-cache 무효화 수행 | 새 명령어 인출 일관성 확보 |

#### 한줄 요약
- 경로 분리는 성능 수단이지만, DMA·자기 수정 코드가 있으면 캐시 동기화까지 함께 설계해야 분리의 이점이 유지된다.

## Ⅶ. 결론

- 동시 명령어 인출·데이터 접근 대역폭이 병목이면 **수정 하버드** 계열을, 저장 공간 유연성과 구현 단순성이 우선이면 **폰 노이만** 구조를 선택

#### 한줄 요약
- 구조 이름보다 실제 워크로드가 명령어와 데이터를 얼마나 동시에 접근하는지가 선택 기준이다.
