## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 아키텍처(Von Neumann Architecture)**: 명령어와 데이터를 하나의 메모리 및 접근 경로에서 다루는 컴퓨터 구조입니다.
- **하버드 아키텍처(Harvard Architecture)**: 명령어와 데이터를 각자의 메모리 및 접근 경로로 분리하는 컴퓨터 구조입니다.
- **수정 하버드 아키텍처(Modified Harvard Architecture)**: 가까운 캐시는 분리하고 하위 메모리는 공유하는 절충 구조입니다.

</details>

- 정의/개념: 명령어와 데이터의 저장·전송 자원을 정하는 **메모리 접근 구조**
- 배경/필요성: 명령 인출과 데이터 접근의 **대역폭 경합** 조절

#### 한줄 요약

- 폰 노이만은 한 길을 함께 쓰고, 하버드는 명령어와 데이터의 길을 나눠 쓰는 구조입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **폰 노이만 병목(Von Neumann Bottleneck)**: 명령어와 데이터가 공유 경로의 대역폭을 경쟁하며 생기는 처리 제약입니다.
- **명령어 인출(Instruction Fetch)**: 프로세서가 다음에 실행할 명령어를 메모리에서 가져오는 동작입니다.
- **로드/스토어(Load/Store)**: 메모리와 레지스터 사이에서 데이터를 읽거나 쓰는 접근 동작입니다.

</details>

- 폰 노이만: 통합 저장소 기반의 **용량 활용 유연성**
- 하버드: 인출과 로드/스토어의 **동시 접근 가능성**
- 수정 하버드: 분리 캐시와 통합 메모리의 **계층별 절충**

#### 한줄 요약

- 공유 구조는 저장 공간을 유연하게 쓰고, 분리 구조는 코어 가까이에서 두 접근을 겹칠 수 있습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache, I-cache)**: 자주 실행하는 명령어를 가까이 보관해 인출 지연을 줄이는 캐시입니다.
- **데이터 캐시(Data Cache, D-cache)**: 자주 읽거나 쓰는 데이터를 가까이 보관해 접근 지연을 줄이는 캐시입니다.
- **통합 메모리(Unified Memory)**: 명령어와 데이터가 같은 물리 저장 자원을 공유하는 메모리입니다.

</details>

```text
[프로세서 메모리 구조]
├─ 폰 노이만 구조
│  └─ 통합 메모리
├─ 하버드 구조
│  ├─ 명령어 메모리
│  └─ 데이터 메모리
└─ 수정 하버드 구조
   ├─ I-cache
   ├─ D-cache
   └─ 통합 메모리
```

| 구성요소 | 책임 |
|:---|:---|
| 통합 메모리 | 명령어와 데이터의 공동 저장 |
| 명령어 메모리 | 실행 코드의 독립 저장 |
| 데이터 메모리 | 피연산자와 결과의 독립 저장 |
| I-cache | 명령어 인출 지연 감소 |
| D-cache | 데이터 접근 지연 감소 |

#### 한줄 요약

- 순수 구조는 저장소부터 나뉘지만, 수정 하버드는 캐시만 나누고 하위 메모리를 공유합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 미스(Cache Miss)**: 필요한 명령어 또는 데이터가 캐시에 없어 하위 메모리를 접근하는 상황입니다.
- **메모리 일관성(Memory Coherency)**: 여러 저장 사본에서 읽는 값이 올바르게 보이도록 맞추는 성질입니다.

</details>

```text
[1. 명령어 인출]
          │
          ▼
[2. 명령어 해석]
          │
          ▼
[3. 데이터 접근]
          │
          ▼
[4. 결과 기록]
```

동작 원리:

1. 명령어 인출: 공유 또는 명령 경로에서 다음 명령어 확보
2. 명령어 해석: 연산과 데이터 접근 필요 여부 판독
3. 데이터 접근: 공유 또는 데이터 경로에서 피연산자 확보
4. 결과 기록: 연산 결과와 상태를 레지스터 또는 메모리에 반영

#### 한줄 요약

- 하버드 구조는 1번과 3번의 경로를 분리하지만, 캐시 미스 뒤의 하위 메모리는 다시 공유될 수 있습니다.

## Ⅴ. 종류 및 비교

| 구조 유형 | 폰 노이만 | 하버드 | 수정 하버드 |
|:---|:---|:---|:---|
| 적용 기준 | 용량 공유와 단순한 주소 관리 | 동시 인출·데이터 접근 필요 | 범용 OS와 코어 대역폭 동시 요구 |
| 핵심 특징 | 통합 메모리와 공유 경로 | 분리 메모리와 전용 경로 | I-cache·D-cache 분리와 하위 통합 |
| 한계 | 공유 경로의 병목 가능성 | 공간 배분과 코드 갱신 제약 | 하위 계층 경합과 일관성 관리 |

#### 한줄 요약

- 메모리 활용이 우선이면 통합, 동시 접근이 우선이면 분리, 둘 다 필요하면 수정 하버드를 고릅니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 유지보수(Cache Maintenance)**: 캐시의 데이터를 정리하거나 무효화해 메모리 사본 상태를 맞추는 작업입니다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 주변 장치가 CPU 개입을 줄이고 메모리와 데이터를 전송하는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 경로에서 인출과 데이터 접근 충돌 | I-cache·D-cache 분리와 접근 패턴 분석 | 코어 근처 대역폭 경합 완화 |
| DMA가 캐시 사본과 다른 값을 갱신 | 캐시 유지보수와 버퍼 소유권 동기화 | 데이터 사본 불일치 방지 |
| 데이터 경로로 생성한 코드를 즉시 실행 | D-cache 정리와 I-cache 무효화 적용 | 새 명령어 인출의 일관성 확보 |

#### 한줄 요약

- 경로 분리는 성능 수단이고, 실제 시스템에서는 DMA와 코드 갱신까지 포함해 사본을 맞춰야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **워크로드(Workload)**: 시스템이 실제로 처리하는 명령어, 데이터, 입출력 접근의 조합입니다.

</details>

- **워크로드**의 동시 접근과 저장소 공유 수준을 기준으로, 대역폭이 우선이면 하버드 계열을, 용량 유연성이 우선이면 폰 노이만 계열을 선택

#### 한줄 요약

- 구조 이름보다 실제 프로그램이 명령어와 데이터를 얼마나 동시에 읽고 쓰는지가 선택 기준입니다.
