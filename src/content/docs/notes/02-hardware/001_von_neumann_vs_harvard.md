## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 구조(Von Neumann Architecture, VNA)**: 명령어와 데이터가 단일 메모리와 데이터/주소 버스를 공유하여 순차 접근 시 병목이 발생할 수 있는 프로그램 내장 방식이다.
- **하버드 구조(Harvard Architecture, HA)**: 명령어용 메모리와 데이터용 메모리, 물리적 버스를 분리하여 병렬 처리를 지원하는 아키텍처이다.
- **컴퓨터 아키텍처(Computer Architecture)**: 프로세서, 메모리, I/O 버스의 하위 하드웨어 조직과 명령어 집합을 정의하는 컴퓨터 설계 체계이다.
- **동시 접근 병목(Bus Contention)**: 명령어 인출과 데이터 처리가 동일 버스를 두고 경쟁하여 파이프라인이 정지하는 현상이다.

</details>

- 정의: 명령어와 데이터의 저장 및 접근 버스를 공유할지 분리할지에 따라 프로세서 설계를 분류하는 **컴퓨터 아키텍처** 규격
- 배경: 단일 버스 구조에서 발생하는 **동시 접근 병목**을 해결하고 명령어 파이프라인 효율을 극대화하기 위함

#### 한줄 요약

- 폰 노이만 구조는 단일 버스로 순차 접근 병목을 유발하며, 하버드 구조는 물리적으로 버스를 분리하여 완전한 병렬 처리를 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수정 하버드 구조(Modified Harvard Architecture, MHA)**: 메인 메모리는 단일 공간으로 통합하고 CPU 내부 L1 캐시만 명령어/데이터로 분리한 절충형 아키텍처이다.
- **L1 캐시 분리(L1 Cache Split)**: 코어 내부 캐시를 명령어 전용(I-Cache)과 데이터 전용(D-Cache)으로 분리하여 파이프라인 정지를 예방하는 설계이다.
- **주기억 통합(Unified Main Memory)**: 코드와 데이터가 하나의 외부 메모리 공간을 시분할로 공유하여 메모리 용량 낭비를 막는 방식이다.
- **명령어•데이터 동시 접근**: 독립된 버스를 통해 명령어를 가져오는 동작과 데이터를 읽고 쓰는 동작을 동일 주기 내에서 수행하는 원리이다.
- **메모리 용량 배분(Memory Partitioning)**: 코드 영역과 데이터 영역의 크기를 가변 할당하여 남는 공간 없이 활용하는 기법이다.

</details>

- 물리적 버스 분리로 **명령어•데이터 동시 접근**을 실현하여 파이프라인 정지를 원천 제거함.
- 주소 공간 단일화로 상황에 맞춘 동적 **메모리 용량 배분**을 지원하여 낭비 요소를 없앰.
- **주기억 통합**의 용량 유연성과 **L1 캐시 분리**의 대역폭 확장을 최적으로 결합함.
- 범용 CPU(x86, ARM 등) 설계 시 절충형 모델인 **수정 하버드 구조**를 글로벌 표준으로 채택함.

#### 한줄 요약

- 메인 메모리 통합과 L1 캐시 분리를 결합한 수정 하버드 구조로 메모리 유연성과 파이프라인 성능을 동시에 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 전용 경로(Instruction Dedicated Bus)**: 하버드 구조에서 명령어를 CPU 제어부로 전달하기 위해서만 배정된 독립 버스이다.
- **데이터 전용 경로(Data Dedicated Bus)**: 하버드 구조에서 산술 연산용 피연산자를 이동시키는 전용 버스이다.
- **공유 경로(Shared Bus)**: 폰 노이만 구조에서 명령어와 데이터가 시분할 방식으로 함께 사용하는 단일 통로이다.

</details>

```text
폰 노이만 구조
[CPU] <==== 공유 버스 ====> [통합 메모리]

하버드 구조
      <== 명령어 버스 ==> [명령어 메모리]
[CPU]
      <==== 데이터 버스 ====> [데이터 메모리]
```

가지의 의미: 단일 공유 버스를 통한 시분할 병목 전송과, 완전 분리 버스를 통한 병렬 동시 전송 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| CPU | 명령어 인출 및 데이터 접근 제어 주체 |
| 명령어 메모리•버스 | **명령어 전용 경로**로 코드를 연속 인출 |
| 데이터 메모리•버스 | **데이터 전용 경로**로 피연산자 독립 전송 |
| 통합 메모리•버스 | **공유 경로** 하나로 코드 및 데이터 시분할 전송 |

#### 한줄 요약

- 폰 노이만 구조는 단일 공유 버스를 통한 시분할 구조이며, 하버드 구조는 듀얼 전용 버스를 사용해 병렬성을 실현한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **공유 버스 접근(Shared Bus Access)**: 동일 물리 버스 상에서 타임 슬롯을 나누어 명령어와 데이터를 번갈아 인출하는 방식이다.
- **분리 버스 접근(Split Bus Access)**: 독립된 두 컨트롤러와 라인으로 명령어 인출과 데이터 억세스를 동일 사이클에 완결하는 방식이다.

</details>

```text
아키텍처별 메모리 접근
├─ 폰 노이만
│  └─ 1. 공유 버스 접근: 명령어 인출 → 버스 대기 → 데이터 접근
└─ 하버드
   └─ 2. 분리 버스 접근
         ├─ 명령어 버스: 명령어 인출 동시 수행
         └─ 데이터 버스: 데이터 접근 동시 수행
```

### 동작 원리

1. 공유 버스 접근: 명령어 인출로 데이터 버스가 점유되어, 다음 데이터 억세스를 위해 파이프라인에 대기 주기가 발생함.
2. 분리 버스 접근: 명령어와 데이터가 물리적으로 분리된 버스를 통과하므로 동일 클록 사이클 내에서 간섭 없이 동시 처리됨.

#### 한줄 요약

- 폰 노이만 구조는 시분할 순차 접근 방식을 취하며, 하버드 구조는 독립 버스를 활용한 병렬 접근 방식을 취한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 주소 공간(Unified Address Space)**: 프로그램과 변수가 단일 메인 메모리의 논리 주소 영역에 통합 매핑되는 구조이다.
- **실시간 신호 처리(Real-Time Signal Processing)**: DSP 등에서 확정적 실행 시간(Deterministic Latency)이 요구되는 처리이다.
- **ISA(Instruction Set Architecture)**: 하드웨어가 실행하는 기계어 명령 집합 및 레지스터 세트 사양 규격이다.
- **대역폭 제한(Bandwidth Limitation)**: 버스 대역폭 한계로 데이터 전송이 연산 속도를 따라가지 못하는 제약이다.
- **용량 고정(Fixed Partitioning)**: 메모리가 격리되어 일방의 메모리가 부족해도 타방을 가져다 쓰지 못하는 비효율이다.
- **명령 캐시 동기화(Instruction Cache Synchronization)**: 동적 코드 변경 시 데이터 캐시 갱신 내용을 명령 캐시에 즉각 반영하는 연산이다.

</details>

| 아키텍처 | 폰 노이만 구조 | 하버드 구조 | 수정 하버드 구조 |
|:---|:---|:---|:---|
| 적용 환경 | 용량 가변성이 큰 일반 컴퓨팅 | **실시간 신호 처리** 및 초고속 MCU | 최신 범용 **ISA** 고성능 프로세서 |
| 핵심 특징 | **단일 주소 공간** 기반 설계 단순성 | 메모리와 버스의 물리적 완전 격리 | 메인 메모리는 **주기억 통합**, 코어는 **L1 캐시 분리** |
| 치명적 한계 | 공유 버스 경쟁에 따른 **대역폭 제한** | 공간 재배치가 불가능한 **용량 고정** | JIT 컴파일 시 복잡한 **명령 캐시 동기화** 유발 |

#### 한줄 요약

- 버스 병목을 가진 폰 노이만, 메모리 크기 제약이 있는 하버드를 절충하여 L1 캐시 분리 기반의 수정 하버드로 진화했다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **폰 노이만 병목(Von Neumann Bottleneck)**: 메모리와 프로세서 간 전송 속도 격차와 버스 공유로 인한 실행 지연 문제이다.
- **대기 주기(Wait Cycle)**: 느린 메모리 응답을 기다리기 위해 CPU 연산 파이프라인이 멈추는 시간이다.
- **캐시 적중률(Cache Hit Rate)**: 메모리 주소가 캐시에 존재하여 주기억장치에 접근하지 않고 처리되는 확률이다.
- **프리페치(Prefetch)**: 향후 참조될 데이터를 미리 상위 캐시로 전송하여 버스 지연을 은닉하는 기법이다.
- **버스 대역폭(Bus Bandwidth)**: 단위 시간당 버스를 통해 이동시킬 수 있는 최대 정보량이다.
- **명령 캐시 무효화(Instruction Cache Invalidation)**: 구버전 명령어가 I-Cache에 남아 오류를 유발하지 않도록 데이터를 파기하는 연산이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **폰 노이만 병목**에 따른 파이프라인 **대기 주기** 증대 | **캐시 적중률** 기반 **프리페치** 및 다중 채널 **버스 대역폭** 확장 | 메모리 접근 지연 은닉 및 처리량 증가 |
| JIT 컴파일 중 D-Cache의 기계어와 I-Cache 내용 불일치 | D-Cache 정리 후 **명령 캐시 무효화** 연산(ISB 등) 명시적 호출 | 캐시 일관성 확보 및 올바른 코드 실행 보장 |
| 순수 하버드 도입 시 메모리 단편화 및 **용량 고정** 심화 | 주기억은 통합하고 캐시만 분리하는 **수정 하버드 구조** 칩 설계 | 동적 공간 활용 극대화 |

#### 한줄 요약

- 프리페치를 통해 대역폭 한계를 완화하고, 수정 하버드 구조에서는 명령 캐시 무효화를 통해 데이터 일관성을 지킨다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **디지털 신호 처리기(DSP)**: 음성, 영상 신호 등을 고속 병렬 수학 연산으로 처리하는 전용 프로세서이다.
- **구조 선택 기준(Architecture Selection Criteria)**: 실시간성, 공간 효율성, 비용 등을 종합적으로 고려한 설계 판단 지표이다.

</details>

- 유연성이 중요한 범용 CPU는 **수정 하버드**, 결정성이 필수인 DSP는 **하버드 구조** 채택

#### 한줄 요약

- 범용 시스템에는 메모리 활용이 좋은 수정 하버드를, 결정적 실시간 시스템에는 순수 하버드 구조를 선택한다.
