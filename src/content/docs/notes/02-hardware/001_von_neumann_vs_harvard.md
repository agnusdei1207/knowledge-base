## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 구조(Von Neumann Architecture, VNA)**: 명령어와 데이터가 단일 메모리와 버스를 공유하는 프로그램 내장 방식.
- **하버드 구조(Harvard Architecture, HA)**: 명령어와 데이터의 메모리 및 버스를 물리적으로 분리한 아키텍처.
- **동시 접근 병목(Bus Contention)**: 명령어 인출과 데이터 처리가 동일 버스를 공유하여 발생하는 지연 현상.

</details>

- 정의/개념: 명령어와 데이터의 메모리·버스 공유 여부에 따라 프로세서 설계를 분류하는 컴퓨터 아키텍처 규격
- 배경/필요성: 단일 버스 구조의 **폰 노이만 병목(Bus Contention)** 해소 및 명령·데이터 동시 접근을 통한 파이프라인 정지 제거

#### 한줄 요약

- 폰 노이만은 **단일 버스 공유**, 하버드는 **명령·데이터 분리 버스**로 병렬 처리 지원

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수정 하버드 구조(Modified Harvard Architecture, MHA)**: 주기억장치는 통합하고 L1 캐시만 명령어(I)와 데이터(D)로 분리한 절충형 구조.
- **L1 캐시 분리(L1 Split Cache)**: 코어 내부 L1 캐시를 I-Cache와 D-Cache로 독립 분리하여 파이프라인 스톨을 방지하는 설계.

</details>

- 물리적 버스 분리를 통한 명령어·데이터 **동시 접근** 및 파이프라인 정지 제거
- 단일 주소 공간 기반 동적 메모리 용량 배분 및 **낭비 방지**
- 주기억 통합의 유연성과 L1 캐시 분리의 대역폭 확장을 결합한 **수정 하버드 구조** 채택

#### 한줄 요약

- 메인 메모리 통합과 **L1 캐시 분리(I/D)**를 결합해 유연성과 대역폭 동시 확보

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 전용 버스**: 하버드 구조에서 프로그램 코드를 CPU 제어부로 연속 공급하는 전용 통로.
- **데이터 전용 버스**: 하버드 구조에서 연산용 피연산자를 읽고 쓰는 독립 통로.

</details>

```text
폰 노이만 구조 (Von Neumann)
[ CPU ] <══════ 단일 공유 버스 (시분할) ══════> [ 통합 메모리 (Code + Data) ]

하버드 구조 (Harvard)
        <══════ 명령어 전용 버스 ══════> [ 명령어 메모리 (Code) ]
[ CPU ]
        <══════ 데이터 전용 버스 ══════> [ 데이터 메모리 (Data) ]
```

선의 의미: 단일 공유 버스를 통한 시분할 전송과 분리 버스를 통한 병렬 동시 전송 아키텍처 비교.

| 구성요소 | 책임 |
|:---|:---|
| CPU | 명령어 인출 및 데이터 접근 제어 주체 |
| 명령어 메모리•버스 | **명령어 전용 경로**로 코드를 연속 인출 |
| 데이터 메모리•버스 | **데이터 전용 경로**로 피연산자 독립 전송 |
| 통합 메모리•버스 | **공유 경로** 하나로 코드 및 데이터 시분할 전송 |

#### 한줄 요약

- 폰 노이만은 **공유 버스 시분할**, 하버드는 **듀얼 전용 버스 병렬 전송** 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **파이프라인 스톨(Pipeline Stall)**: 버스 점유 경쟁으로 인해 다음 명령어 실행 단계가 멈추는 현상.

</details>

```text
아키텍처별 메모리 접근 흐름
├─ 폰 노이만 (단일 버스)
│  └─ 1. 명령어 인출(IF) ──> 버스 점유 ──> 데이터 접근(MEM) 시 파이프라인 대기(Stall)
└─ 하버드 (분리 버스)
   └─ 2. 분리 버스 동시 접근
         ├─ 명령어 버스: 명령어 인출(IF) 연속 수행
         └─ 데이터 버스: 데이터 읽기/쓰기(MEM) 동시 수행
```

**동작 원리**

1. **공유 버스 접근**: 명령어 인출 동안 버스가 점유되어 데이터 접근 단계에서 파이프라인 대기 발생
2. **분리 버스 접근**: 명령어와 데이터가 독립 버스를 통과하므로 동일 클록 사이클 내 간섭 없이 동시 완료

#### 한줄 요약

- 폰 노이만은 **시분할 대기**, 하버드는 **동일 클록 동시 접근** 방식

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **명령 캐시 무효화(ISB, Instruction Sync Barrier)**: 동적 코드 수정 시 D-Cache 내용을 I-Cache에 즉각 반영하는 동기화 연산.

</details>

| 아키텍처 | 폰 노이만 구조 (Von Neumann) | 하버드 구조 (Harvard) | 수정 하버드 구조 (Modified Harvard) |
|:---|:---|:---|:---|
| 적용 기준 | 일반 범용 컴퓨팅 및 저비용 임베디드 | 실시간 신호 처리(DSP) 및 고속 MCU | 현대 고성능 범용 프로세서(x86, ARM) |
| 핵심 특징 | 단일 주소 공간, 버스 공유, 설계 단순성 | 명령어/데이터 메모리 및 버스 완전 격리 | 주기억장치 통합 및 L1 캐시 분리(I/D) |
| 한계 및 위험 | 버스 경쟁에 따른 폰 노이만 병목 발생 | 코드/데이터 간 메모리 공유 불가(용량 고정) | JIT 컴파일 시 명령 캐시 동기화(ISB) 오버헤드 |

#### 한줄 요약

- 폰 노이만의 병목과 하버드의 고정성을 절충한 **L1 분리형 수정 하버드 구조** 활용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **폰 노이만 병목**: 메모리와 CPU 간 속도 격차 및 버스 공유로 인한 성능 저하 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **폰 노이만 병목**에 따른 파이프라인 대기 | 프리페치 및 다중 채널 **대역폭 확장** | 메모리 접근 지연 은닉 |
| JIT 컴파일 시 I/D 캐시 내용 불일치 | D-Cache 플러시 후 **명령 캐시 무효화** | 캐시 일관성 및 정상 실행 보장 |
| 순수 하버드의 메모리 단편화 | 주기억 통합형 **수정 하버드 구조** 채택 | 동적 메모리 활용 극대화 |

#### 한줄 요약

- **프리페치와 명령 캐시 무효화(ISB)**로 병목 완화 및 일관성 확보

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **아키텍처 트레이드오프**: 범용 시스템의 유연성과 전용 DSP의 결정론적 실시간성 간의 설계 선택.

</details>

- 범용 고성능 CPU는 **수정 하버드 구조**, 결정적 실시간 제어는 **하버드 구조** 채택

#### 한줄 요약

- 용도에 따라 **유연한 수정 하버드**와 **결정론적 순수 하버드** 선택
