## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **폰 노이만 구조(Von Neumann Architecture)**: 명령어와 데이터가 하나의 메모리와 버스를 공유하는 컴퓨터 구조.
- **하버드 구조(Harvard Architecture)**: 명령어와 데이터의 메모리와 버스를 물리적으로 분리하는 컴퓨터 구조.
- **컴퓨터 아키텍처(Computer Architecture)**: 프로세서•메모리•입출력 경로의 구성과 동작 규칙을 정의하는 체계.
- **동시 접근 병목(Bus Contention)**: 명령어 인출과 데이터 접근이 같은 버스를 두고 경쟁해 프로세서가 대기하는 현상.

</details>

- 정의/개념: 명령어와 데이터의 메모리·버스 공유 여부에 따라 단일 경로 공유형과 물리적 경로 분리형으로 구분되는 **컴퓨터 아키텍처** 분류
- 배경/필요성: 단일 버스 공유 시 명령어 인출과 데이터 읽기·쓰기의 동시 요청으로 버스 경합 및 처리기 대기 병목 발생

#### 한줄 요약
- 폰 노이만 구조는 단일 버스 공유에 의한 폰 노이만 병목을 유발하며, 하버드 구조는 물리적 분리 버스를 통해 명령어 인출과 데이터 접근의 병렬 수행을 지원한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 공간(Address Space)**: 프로세서가 접근할 수 있는 메모리 주소의 전체 범위.
- **수정 하버드 구조(Modified Harvard Architecture)**: 주기억장치를 통합하고 L1 캐시를 명령/데이터로 분리해 용량 유연성과 동시 접근을 절충한 구조.
- **1단계 캐시(Level 1 Cache, L1 Cache)**: CPU 코어에 가장 가까운 소용량 고속 캐시.
- **명령어•데이터 동시 접근(Simultaneous Access)**: 분리된 경로에서 명령어 인출과 데이터 접근을 같은 시점에 수행하는 방식.
- **메모리 용량 배분(Memory Partitioning)**: 단일 주소 공간 내에서 명령어와 데이터 영역의 크기를 프로그램 실행 조건에 따라 가변 할당하는 작업.
- **주기억 통합(Unified Main Memory)**: 명령어와 데이터가 하나의 주기억장치를 공유하는 구성.
- **L1 캐시 분리(L1 Cache Split)**: 명령 캐시(I-Cache)와 데이터 캐시(D-Cache)를 코어 가까이에서 나누는 구성.

</details>

- 경로 분리로 **명령어•데이터 동시 접근** 시 처리량 증가
- 주소 공간 통합으로 코드·데이터 간 **메모리 용량 배분** 제약 완화
- **주기억 통합**•**L1 캐시 분리**로 용량 유연성과 동시 접근 절충
- 이 절충 구조가 **수정 하버드 구조**

#### 한줄 요약
- 독립된 버스로 동시 인출·접근을 지원하되, 메인 메모리는 통합하고 L1 캐시 계층을 분리한 수정 하버드 아키텍처로 공간 효율성을 확보한다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령어 실행과 메모리 접근 요청을 생성하는 핵심 장치.
- **버스(Bus)**: CPU•메모리•입출력장치 사이에서 신호를 전달하는 통로.
- **명령어 전용 경로(Instruction Bus)**: 명령어 접근에 별도 메모리와 버스를 제공하는 통로.
- **데이터 전용 경로(Data Bus)**: 데이터 접근에 별도 메모리와 버스를 제공하는 통로.
- **공유 경로(Shared Bus)**: 명령어와 데이터가 같은 메모리와 버스를 사용하는 단일 통로.

</details>

```text
폰 노이만 구조
[CPU] ----- [통합 명령어·데이터 메모리]
             공유 버스

하버드 구조
          +-- [명령어 메모리]
[CPU] ----+
          `-- [데이터 메모리]
             분리 버스
```

선의 의미: 폰 노이만은 공유 연결, 하버드는 명령어·데이터의 분리 연결.

| 구성요소 | 책임 |
|:---|:---|
| CPU | 명령어 인출과 데이터 읽기•쓰기 요청 생성 |
| 명령어 메모리•버스 | 하버드의 **명령어 전용 경로** 제공 |
| 데이터 메모리•버스 | 하버드의 **데이터 전용 경로** 제공 |
| 통합 메모리•버스 | 폰 노이만의 **공유 경로** 제공 |

#### 한줄 요약
- 폰 노이만은 단일 Shared Bus, 하버드는 Instruction/Data Dedicated Bus 인프라를 형성한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **분리 경로(Separate Path)**: 명령어와 데이터가 서로 다른 메모리와 버스를 사용하는 통로.
- **공유 버스 접근(Shared Bus Access)**: 명령어 인출과 데이터 접근이 하나의 버스를 순서대로 사용하는 방식.
- **분리 버스 접근(Split Bus Access)**: 명령어 인출과 데이터 접근이 서로 다른 버스를 동시에 사용하는 방식.

</details>

```text
명령어•데이터 접근 요청
          │
          ▼
       구조별 접근
          ├─ 폰 노이만: 1. 공유 버스 접근
          │              └─ 인출·데이터 접근 순차 처리
          └─ 하버드: 2. 분리 버스 접근
                         ├─ 명령어 인출
                         └─ 데이터 접근
```

### 동작 원리

1. **공유 버스 접근**: 명령어 인출과 데이터 접근을 한 버스에서 순차 처리.
2. **분리 버스 접근**: 명령어 인출과 데이터 접근을 별도 버스에서 동시 처리. 하버드의 **분리 경로**가 두 접근을 독립 운반.

#### 한줄 요약
- 폰 노이만 구조는 Time-multiplexed Bus Access, 하버드 구조는 Dual Independent Bus Pipeline Access 방식으로 작동한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단일 주소 공간(Unified Address Space)**: 명령어와 데이터가 같은 주소 체계를 사용하는 구성.
- **실시간 신호 처리(Real-Time Signal Processing)**: 정해진 시간 안에 연속 신호 데이터를 처리해야 하는 작업.
- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 프로세서의 명령어와 레지스터 동작 규격.
- **대역폭 제한(Bandwidth Limitation)**: 공유 버스의 전송량 한계로 성능이 제한되는 상태.
- **용량 고정(Fixed Partition)**: 분리된 명령어•데이터 메모리 사이에서 남는 공간을 서로 빌려 쓸 수 없는 제약.
- **명령 캐시 동기화(Instruction Cache Synchronization)**: 코드 변경 내용을 명령 캐시에 반영해 실행 명령과 메모리의 코드를 일치시키는 작업.

</details>

| 컴퓨터 구조 | 폰 노이만 구조 | 하버드 구조 | 수정 하버드 구조 |
|:---|:---|:---|:---|
| 적용 기준 | 코드·데이터 용량 비율이 자주 변할 때 | **실시간 신호 처리**에 동시 접근이 필요할 때 | 범용 ISA에서 용량·처리량을 절충할 때 |
| 핵심 특징 | **단일 주소 공간**과 버스 공유 | 명령어·데이터 메모리와 버스의 물리적 분리 | **주기억 통합**•**L1 캐시 분리** |
| 한계 | 공유 버스 경합에 따른 **대역폭 제한** | 한쪽 여유 공간을 다른 쪽이 쓰지 못하는 **용량 고정** | 코드 변경 후 **명령 캐시 동기화** 부담 |

> 요약: 하버드의 **용량 고정**을 주기억 통합으로 완화한 수정 하버드가 핵심.

#### 한줄 요약
- Bus Contention 기반의 대역폭 한계(Von Neumann), Static Memory Partitioning 제약(Harvard), L1 Split Cache 구조(Modified Harvard)로 서술된다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **폰 노이만 병목(Von Neumann Bottleneck)**: 단일 버스의 메모리 전송 대기가 CPU 성능을 제한하는 현상.
- **명령 캐시 무효화(Instruction Cache Invalidation)**: 오래된 명령어 사본을 캐시에서 제거하는 절차.
- **프리페치(Prefetch)**: 곧 사용할 명령어나 데이터를 미리 캐시에 가져오는 처리.
- **버스 대역폭(Bus Bandwidth)**: 버스가 단위 시간에 전송할 수 있는 데이터양.
- **캐시 적중률(Cache Hit Rate)**: 요청값을 캐시에서 찾은 비율.
- **대기 주기(Wait Cycle)**: 버스나 메모리 응답을 기다린 클록 주기 수.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **폰 노이만 병목**으로 CPU 대기 | **캐시 적중률**•**대기 주기** 측정 후 **프리페치**•**버스 대역폭** 확대 | 명령 처리량 증가 |
| 코드 갱신 뒤 명령 캐시에 이전 코드 잔존 | 데이터 캐시 정리 후 **명령 캐시 무효화** | 갱신 코드와 실행 명령 일치 |
| 분리 메모리의 **용량 고정** | 주기억을 공유하는 **수정 하버드 구조** 채택 | 코드·데이터 간 용량 재배분 |

#### 한줄 요약
- Cache Line Flush & Instruction Cache Invalidation(I-Cache Invalidation)을 통한 Cache Coherency 유지 및 프리페치/Bus Pipeline 최적화를 수행한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **디지털 신호 처리기(Digital Signal Processor, DSP)**: 반복 신호 연산에 특화된 전용 프로세서.
- **결정적 처리량(Deterministic Throughput)**: 실행 조건이 같을 때 일정한 작업량을 보장하는 성질.
- **구조 선택 기준**: 용량 유연성과 명령어•데이터 동시 접근 요구에 따라 컴퓨터 구조를 결정하는 기준.

</details>

- **구조 선택 기준**에 따라 용량 유연성 우선 시 **수정 하버드 구조**, **DSP**처럼 **결정적 처리량** 필수 시 **하버드 구조** 선택

#### 한줄 요약
- 범용 프로세서에는 Modified Harvard Architecture(L1 Split Cache), Deterministic Latency가 필수적인 DSP/임베디드에는 순수 Harvard Architecture를 채택한다.
