## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 아키텍처(Von Neumann Architecture)**: 단일 메모리 공간과 단일 시스템 버스를 공유하여 명령어 인출과 데이터 접근을 순차적으로 처리하는 컴퓨터 구조.
- **하버드 아키텍처(Harvard Architecture)**: 명령어 메모리/버스와 데이터 메모리/버스를 물리적으로 분리하여 명령어 인출과 데이터 접근의 동시 처리를 지원하는 컴퓨터 구조.

</details>

- 정의/개념: 명령어와 데이터가 메모리 버스를 공유하는 **폰 노이만 아키텍처** 및 경로를 분리하는 **하버드 아키텍처** 기반 갈리는 컴퓨터 구조 선택
- 배경/필요성: 단일 버스에서 명령어 인출과 데이터 접근이 경합해 처리량이 제한됨

#### 한줄 요약
- 폰 노이만은 한 길을 명령어와 데이터가 함께 쓰고, 하버드는 두 길을 따로 내어 동시에 달릴 수 있게 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수정 하버드 아키텍처(Modified Harvard Architecture)**: L1 캐시 계층에서 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)를 분리하고 하위 메모리는 단일 통합 공간으로 공유하는 절충형 구조.
- **폰 노이만 병목(Von Neumann Bottleneck)**: 명령어 인출과 데이터 메모리 접근이 단일 공유 버스의 대역폭을 경합함으로써 CPU 처리 성능이 버스 전송 속도에 제약되는 현상.
- **명령어 인출(Instruction Fetch)**: 프로그램 카운터(PC)가 가리키는 메모리 주소에서 실행할 명령어를 CPU 내부 레지스터로 가져오는 파이프라인 첫 단계.

</details>

- 폰 노이만: 공유 경로의 **폰 노이만 병목** 기반 명령어 인출과 데이터 접근이 순차화
- 하버드: 명령어·데이터 전용 경로 분리를 통한 동시 접근으로 처리량 향상
- 수정 하버드: L1 캐시만 분리해 병목을 완화하고 하위 통합 메모리로 공간 유연성 보존

#### 한줄 요약
- 공유 구조는 유연하지만 목이 막히고, 분리 구조는 빠르지만 공간 배분이 고정된다는 상충이 수정 하버드로 절충된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache, I-cache)**: 명령어 인출 전용 고속 캐시로, 데이터 접근과의 버스 경합을 차단하고 연속적인 명령어 공급 대역폭을 보장하는 메모리.
- **데이터 캐시(Data Cache, D-cache)**: 데이터 읽기 및 쓰기 연산 전용 고속 캐시로, 명령어 인출 파이프라인과 독립적인 데이터 전송 경로를 제공하는 메모리.
- **통합 메모리(Unified Memory)**: 명령어와 데이터가 동일한 물리적 주소 공간과 메모리 채널을 공유하는 단일 저장 계층.

</details>

```text
폰 노이만 구조
└─ 통합 메모리 ─── 공유 버스 ─── CPU

하버드 구조
├─ 명령어 메모리 ─── 명령 버스 ─┐
└─ 데이터 메모리 ─── 데이터 버스 ┤── CPU

수정 하버드 구조
├─ I-cache ─┐
├─ D-cache ─┼── CPU
└─ 통합 메모리 (공유)
```

선의 의미: `───`는 버스 연결(전송 경로), 가지(`├─`)는 구성요소 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 통합 메모리 | 명령어·데이터 공동 저장 및 주소 공간 제공 |
| 명령어 메모리 | 실행 코드 독립 저장·**명령어 인출** 전용 대역폭 |
| 데이터 메모리 | 피연산자·결과 독립 저장·데이터 접근 전용 대역폭 |
| I-cache | 명령어 인출 지연 감소·데이터 접근과 경합 차단 |
| D-cache | 데이터 접근 지연 감소·명령어 인출과 경합 차단 |

#### 한줄 요약
- 순수 구조는 저장소부터 나뉘지만, 수정 하버드는 캐시 계층만 나누고 아래 메모리는 합쳐 공간 낭비를 줄인다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 유지보수(Cache Maintenance)**: I-Cache와 D-Cache 간의 데이터 불일치를 방지하기 위해 캐시 플러시(Flush) 및 무효화(Invalidate)를 수행하는 일관성 제어 동작.
- **자기 수정 코드(Self-Modifying Code)**: 실행 중 프로그램 데이터 영역에서 생성 또는 수정한 기계어 명령어를 메모리에 기록한 후 즉시 실행하는 코드 패턴.

</details>

```text
명령어 인출과 데이터 접근 발생
              │
       접근 경로가 분리됐는가?
          ┌───┴───┐
        아니오     예
          │        │
   공유 버스 경합  저장소까지 분리됐는가?
                   ┌───┴───┐
                 아니오     예
                   │        │
            분리 캐시 동시 접근  독립 메모리 동시 접근
                   │
          캐시 미스 시 통합 메모리 접근
```

분기 결과: 공유 경로는 직렬화되고, 캐시 또는 저장소 분리는 동시 접근을 허용

#### 한줄 요약
- 분리 경로의 이점은 동시 접근이지만, 자기 수정 코드가 있으면 두 캐시를 명시적으로 동기화해야 그 이점을 지킬 수 있다.

## Ⅴ. 종류 및 비교

| 구조 유형 | 폰 노이만 | 수정 하버드 | 하버드 |
|:---|:---|:---|:---|
| 적용 기준 | 저장 공간 유연성 우선, 동시 접근 불필요 | 범용 OS와 코어 대역폭을 동시에 요구 | 동시 인출·데이터 접근 필수, 공간 고정 허용 |
| 핵심 특징 | 통합 메모리·공유 버스 | I-cache·D-cache 분리·하위 **통합 메모리** | 물리 분리 메모리·전용 버스로 최대 대역폭 확보 |
| 한계 | 공유 버스의 **폰 노이만 병목** | 자기 수정 코드 시 캐시 유지보수 필요 | 코드·데이터 공간 고정 배분·갱신 제약 |

#### 한줄 요약
- 저장 공간 유연성이 우선이면 폰 노이만, 동시 접근이 필수면 하버드, 둘 다 필요하면 수정 하버드가 현실적 선택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 주변장치와 주기억장치 간에 고속으로 대용량 데이터를 직접 전송하는 하드웨어 제어 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 버스에서 명령어 인출·데이터 접근 직렬화 | I-cache·D-cache 분리 및 접근 패턴 분석 | 코어 근방 **폰 노이만 병목** 완화 |
| DMA가 D-cache 사본과 다른 메모리 값 갱신 | **캐시 유지보수**·버퍼 소유권 전환 동기화 | 데이터 사본 불일치 방지 |
| 자기 수정 코드 실행 시 I-cache 오래된 명령어 인출 | D-cache 플러시 후 I-cache 무효화 수행 | 새 명령어 인출 일관성 확보 |

#### 한줄 요약
- 경로 분리는 성능 수단이지만, DMA·자기 수정 코드가 있으면 캐시 동기화까지 함께 설계해야 분리의 이점이 유지된다.

## Ⅶ. 결론

- 명령어·데이터 동시성과 주소 공간 유연성을 함께 요구하는 범용 CPU는 **수정 하버드 아키텍처** 유지, 저장소까지 분리 가능한 고정 워크로드는 **하버드 아키텍처** 선택

#### 한줄 요약
- 구조 이름보다 실제 워크로드가 명령어와 데이터를 얼마나 동시에 접근하는지가 선택 기준이다.
