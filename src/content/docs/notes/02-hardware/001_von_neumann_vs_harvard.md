## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **폰 노이만 구조**: 명령어와 데이터가 하나의 메모리와 버스를 공유하는 컴퓨터 구조이다.
- **하버드 구조**: 명령어와 데이터의 메모리와 버스를 분리하는 컴퓨터 구조이다.
- **컴퓨터 아키텍처**: 프로세서•메모리•입출력 경로의 구성과 동작 규칙이다.
- **동시 접근 병목**: 명령어 인출과 데이터 접근이 같은 버스를 두고 경쟁해 프로세서가 대기하는 현상이다.

</details>

- 정의/개념: **컴퓨터 아키텍처**에서 **폰 노이만 구조**는 명령어•데이터 경로를 공유하고 **하버드 구조**는 두 경로를 분리한다.
- 배경/필요성: 공유 버스에서는 명령어 인출과 데이터 접근의 **동시 접근 병목**이 발생할 수 있다.

#### 한줄 요약
- 폰 노이만 구조는 명령어와 데이터가 같은 경로를 공유해 접근이 겹치면 대기하고, 하버드 구조는 경로를 분리해 동시 접근한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 공간**: 프로세서가 접근할 수 있는 메모리 주소의 전체 범위이다.
- **수정 하버드 구조**: 주기억장치를 통합하고 L1 캐시를 분리한 구조이다.
- **1단계 캐시(Level 1 Cache, L1 캐시)**: CPU 코어에 가장 가까운 소용량 고속 캐시이다.
- **명령어•데이터 동시 접근**: 분리된 경로에서 명령어 인출과 데이터 접근을 같은 시점에 수행하는 방식이다.
- **메모리 용량 배분**: 명령어와 데이터의 저장 공간 크기를 필요에 따라 나누는 작업이다.
- **주기억 통합**: 명령어와 데이터가 하나의 주기억장치를 공유하는 구성이다.
- **L1 캐시 분리**: 명령 캐시와 데이터 캐시를 코어 가까이에서 나누는 구성이다.

</details>

- 경로 분리로 **명령어•데이터 동시 접근** 시 처리량 증가한다.
- 주소 공간 통합으로 코드·데이터 간 **메모리 용량 배분** 제약을 완화한다.
- **주기억 통합**•**L1 캐시 분리**로 용량 유연성과 동시 접근을 절충한다.
- 이 절충 구조가 **수정 하버드 구조**이다.

#### 한줄 요약
- 경로를 나누면 명령어 인출과 데이터 접근을 함께 처리할 수 있고, 메모리를 합치면 코드와 데이터가 저장 공간을 유연하게 나눠 쓴다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령어 실행과 메모리 접근 요청을 담당하는 장치이다.
- **버스**: CPU•메모리•입출력장치 사이에서 신호를 전달하는 통로이다.
- **명령어 전용 경로**: 명령어 접근에 별도 메모리와 버스를 제공하는 통로이다.
- **데이터 전용 경로**: 데이터 접근에 별도 메모리와 버스를 제공하는 통로이다.
- **공유 경로**: 명령어와 데이터가 같은 메모리와 버스를 사용하는 통로이다.

</details>

```text
폰 노이만 구조
[CPU] ----- [통합 명령어·데이터 메모리]
             공유 버스

하버드 구조
          +-- [명령어 메모리]
[CPU] ----+
          `-- [데이터 메모리]
             분리 버스
```

선의 의미: 폰 노이만은 공유 연결, 하버드는 명령어·데이터의 분리 연결을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| CPU | 명령어 인출과 데이터 읽기•쓰기 요청 생성 |
| 명령어 메모리•버스 | 하버드의 **명령어 전용 경로** 제공 |
| 데이터 메모리•버스 | 하버드의 **데이터 전용 경로** 제공 |
| 통합 메모리•버스 | 폰 노이만의 **공유 경로** 제공 |

#### 한줄 요약
- 폰 노이만은 한 메모리 경로를 공유하고, 하버드는 명령어와 데이터가 서로 다른 메모리 경로에 연결된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **분리 경로**: 명령어와 데이터가 서로 다른 메모리와 버스를 사용하는 통로이다.
- **공유 버스 접근**: 명령어 인출과 데이터 접근이 하나의 버스를 순서대로 사용하는 방식이다.
- **분리 버스 접근**: 명령어 인출과 데이터 접근이 서로 다른 버스를 동시에 사용하는 방식이다.

</details>

```text
명령어•데이터 접근 요청
          │
          ▼
       구조별 접근
          ├─ 폰 노이만: 1. 공유 버스 접근
          │              └─ 인출·데이터 접근 순차 처리
          └─ 하버드: 2. 분리 버스 접근
                         ├─ 명령어 인출
                         └─ 데이터 접근
```

### 동작 원리

1. **공유 버스 접근**: 명령어 인출과 데이터 접근을 한 버스에서 순차 처리한다.
2. **분리 버스 접근**: 명령어 인출과 데이터 접근을 별도 버스에서 동시에 처리한다.
- 하버드의 **분리 경로**가 두 접근을 독립적으로 운반한다.

#### 한줄 요약
- 폰 노이만 구조는 한 통로의 사용 순서를 조정하고, 하버드 구조는 명령어와 데이터를 서로 다른 통로로 동시에 전달한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단일 주소 공간**: 명령어와 데이터가 같은 주소 체계를 사용하는 구성이다.
- **실시간 신호 처리**: 정해진 시간 안에 연속 신호 데이터를 처리하는 작업이다.
- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 프로세서의 명령어와 레지스터 동작 규격이다.
- **대역폭 제한**: 공유 버스의 전송량 한계로 성능이 제한되는 상태이다.
- **용량 고정**: 분리된 명령어•데이터 메모리 사이에서 남는 공간을 서로 빌려 쓸 수 없는 제약이다.
- **명령 캐시 동기화**: 코드 변경 내용을 명령 캐시에 반영해 실행 명령과 메모리의 코드를 일치시키는 작업이다.

</details>

| 컴퓨터 구조 | 폰 노이만 구조 | 하버드 구조 | 수정 하버드 구조 |
|:---|:---|:---|:---|
| 적용 기준 | 코드·데이터 용량 비율이 자주 변할 때 | **실시간 신호 처리**에 동시 접근이 필요할 때 | 범용 ISA에서 용량·처리량을 절충할 때 |
| 핵심 특징 | **단일 주소 공간**과 버스 공유 | 명령어·데이터 메모리와 버스의 물리적 분리 | **주기억 통합**•**L1 캐시 분리** |
| 한계 | 공유 버스 경합에 따른 **대역폭 제한** | 한쪽 여유 공간을 다른 쪽이 쓰지 못하는 **용량 고정** | 코드 변경 후 **명령 캐시 동기화** 부담 |

> 요약: 하버드의 **용량 고정**을 주기억 통합으로 완화한 수정 하버드가 핵심이다.

#### 한줄 요약
- 폰 노이만은 한 경로를 공유하고 하버드는 두 경로를 분리하며, 수정 하버드는 주기억을 합치고 L1 캐시만 나눠 절충한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **폰 노이만 병목**: 단일 버스의 메모리 전송 대기가 CPU 성능을 제한하는 현상이다.
- **명령 캐시 무효화**: 오래된 명령어 사본을 캐시에서 제거하는 절차이다.
- **프리페치(Prefetch)**: 곧 사용할 명령어나 데이터를 미리 캐시에 가져오는 처리이다.
- **버스 대역폭**: 버스가 단위 시간에 전송할 수 있는 데이터양이다.
- **캐시 적중률**: 요청값을 캐시에서 찾은 비율이다.
- **대기 주기**: 버스나 메모리 응답을 기다린 클록 주기 수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **폰 노이만 병목**으로 CPU 대기 | **캐시 적중률**•**대기 주기**를 측정하고 **프리페치**•**버스 대역폭** 확대 | 명령 처리량 증가 |
| 코드 갱신 뒤 명령 캐시에 이전 코드 잔존 | 데이터 캐시 정리 후 **명령 캐시 무효화** | 갱신 코드와 실행 명령 일치 |
| 분리 메모리의 **용량 고정** | 주기억을 공유하는 **수정 하버드 구조** 채택 | 코드·데이터 간 용량 재배분 |

#### 한줄 요약
- 공유 구조는 버스 대기를 줄이고, 분리 구조는 명령 캐시 동기화와 코드·데이터 용량 배분을 함께 관리해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **디지털 신호 처리기(Digital Signal Processor, DSP)**: 반복 신호 연산에 특화된 전용 프로세서이다.
- **결정적 처리량**: 실행 조건이 같을 때 일정한 작업량을 보장하는 성질이다.
- **구조 선택 기준**: 용량 유연성과 명령어•데이터 동시 접근 요구로 컴퓨터 구조를 고르는 기준이다.

</details>

- **구조 선택 기준**에 따라 용량 유연성이 중요하면 **수정 하버드 구조**, **DSP**처럼 **결정적 처리량**을 위한 동시 접근이 중요하면 **하버드 구조**를 선택한다.

#### 한줄 요약
- 범용 시스템은 수정 하버드로 저장 공간을 유연하게 쓰고, 신호 처리 장비는 하버드 구조로 명령어 인출과 데이터 접근을 동시에 수행한다.
