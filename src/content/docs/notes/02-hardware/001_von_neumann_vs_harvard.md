## 미리 알고가기

- **컴퓨터 아키텍처(Computer Architecture)**: CPU·메모리·입출력장치의 구성과 명령어·데이터의 저장·전송 방식을 정의한 시스템 구조
- **중앙처리장치(Central Processing Unit, CPU)**: 메모리에서 명령어와 데이터를 가져와 해독하고 연산을 수행하는 핵심 제어·연산 장치
- **폰 노이만 구조(Von Neumann Architecture)**: 명령어와 데이터를 구분 없이 하나의 메모리와 버스로 처리하는 통합 경로 컴퓨터 아키텍처
- **하버드 구조(Harvard Architecture)**: 명령어 전용 메모리·버스와 데이터 전용 메모리·버스를 물리적으로 분리해 동시 접근을 가능하게 한 구조
- **수정 하버드 구조(Modified Harvard Architecture)**: 주기억장치는 하나로 통합하되 CPU 내부의 L1 캐시를 명령어 캐시와 데이터 캐시로 분리한 현대 CPU 구조
- **폰 노이만 병목(Von Neumann Bottleneck)**: 명령어 인출과 데이터 읽기·쓰기가 단일 버스를 공유하여 CPU 연산 속도보다 메모리 전송 속도가 늦어 성능이 제약되는 현상
- **주소 공간(Address Space)**: CPU 또는 메모리 제어기가 개별 데이터나 명령어를 식별하고 접근할 수 있는 고유 메모리 위치의 전체 범위
- **1단계 캐시(Level 1 Cache, L1 Cache)**: CPU 코어에 가장 가깝게 위치하여 명령어와 데이터의 접근 지연을 최소화하는 최고속 소용량 캐시
- **디지털 신호 처리기(Digital Signal Processor, DSP)**: 음성·영상 신호의 반복 연산을 빠르게 수행하도록 명령·데이터 경로를 분리한 전용 프로세서
- **캐시 일관성(Cache Coherence)**: 분리된 명령어 캐시와 데이터 캐시 또는 다중 코어 캐시 간에 같은 메모리 주소의 데이터가 일치하도록 상태를 유지하는 성질
- **버스(Bus)**: CPU, 메모리, 입출력 장치 간에 주소, 데이터, 제어 신호를 주고받는 공용 전기적 전송 통로
- **주기억장치(Main Memory)**: CPU가 현재 실행 중인 프로그램과 데이터를 보관하는 폰 노이만 구조의 통합 메모리

## Ⅰ. 개요

- 정의/개념: 명령·데이터 경로를 통합·분리한 **컴퓨터 구조**
- 기존 한계: 공유 버스는 동시 접근이 막히는 **폰 노이만 병목**

### 쉽게 이해하기 (학습용)
- 공사장 외길에서 지시서를 든 사람과 자재 수레가 서로 비켜 주느라 번갈아 지나가는 장면이 폰 노이만 병목이고, 답안이 배경 대신 이 막힘을 적은 이유는 길을 둘로 뚫는 하버드 구조가 바로 이 기다림을 없애려고 나왔기 때문이다.

## Ⅱ. 특징

- 경로 분리 여부가 **명령어·데이터 동시 접근** 가능성 좌우
- 주소 공간 통합 여부가 **메모리 용량 배분** 유연성 좌우

### 쉽게 이해하기 (학습용)
- 두 구조의 판단축은 명령어·데이터의 메모리와 버스를 통합할지 분리할지이며, 버스 분리는 동시 접근 성능을 높이고 메모리 통합은 공간 활용과 설계를 단순화한다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    C["CPU"]
    subgraph VN["폰 노이만"]
        V["통합 메모리·버스"]
    end
    subgraph HV["하버드"]
        I["명령어 메모리·버스"]
        D["데이터 메모리·버스"]
    end
    C <-->|명령어·데이터 공유| V
    C <-->|명령어 전용| I
    C <-->|데이터 전용| D
```

| 설계 요소 | 설명 |
|:---|:---|
| CPU | 명령어 인출과 데이터 읽기·쓰기를 제어하는 **연산 주체** |
| 통합 메모리·버스 | 명령어·데이터가 **주소 공간**과 버스를 공유하는 통합 경로 |
| 명령어 메모리·버스 | **명령어 인출** 전용으로 데이터 접근과 분리된 경로 |
| 데이터 메모리·버스 | 연산 **데이터 읽기·쓰기** 전용의 분리 경로 |

> 요약: 통합 경로는 **용량 유연성**, 분리 경로는 **동시 접근성**

### 쉽게 이해하기 (학습용)
- 폰 노이만 구조는 명령어와 데이터가 하나의 메모리·버스를 공유하고, 하버드 구조는 명령어 인출 경로와 데이터 읽기·쓰기 경로를 분리하여 동시에 접근한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant C as CPU
    participant UB as 통합 버스
    participant IB as 명령어 버스
    participant DB as 데이터 버스
    alt 폰 노이만 구조
        C->>UB: 명령어·데이터 순차 요청
        UB-->>C: 시분할 순차 전송
    else 하버드 구조
        C->>IB: 명령어 인출 요청
        C->>DB: 데이터 읽기 요청
        IB-->>C: 명령어 전송
        DB-->>C: 데이터 전송
    end
```

| 절차 | 설명 |
|:---|:---|
| 명령어·데이터 순차 요청 | CPU가 통합 버스에 **명령어·데이터 접근** 교대 요청 |
| 시분할 순차 전송 | 공용 버스의 **시분할 제어**로 한 번에 하나씩 전송 |
| 명령어 인출 요청 | CPU가 명령어 전용 버스에 **인출 요청** 전달 |
| 데이터 읽기 요청 | 같은 주기에 데이터 전용 버스로 **동시 요청** |
| 명령어 전송 | 데이터 접근 대기 없는 **명령어 인출** 완료 |
| 데이터 전송 | 명령어 인출과 겹친 **데이터 확보** 완료 |

> 요약: 통합 버스는 **시분할 순차 접근**, 분리 버스는 **병렬 접근**

### 쉽게 이해하기 (학습용)
- 위 두 줄과 아래 네 줄이 나뉜 이유는 시계 한 칸에 무슨 일이 벌어지는지가 다르기 때문인데, 통합 버스에서는 한 칸에 지시서 하나만 지나가 자재는 다음 칸을 기다리지만, 분리 버스에서는 같은 한 칸에 두 문이 함께 열려 지시서와 자재가 나란히 들어온다.

## Ⅴ. 종류 및 비교

| 컴퓨터 구조 | 폰 노이만 구조 | 하버드 구조 | 수정 하버드 구조 |
|:---|:---|:---|:---|
| 적용 기준 | 명령어·데이터 **용량 비율**이 변하는 경우 | **실시간 신호 처리**에 동시 접근이 필요한 경우 | 범용 ISA에 **고속 인출**이 필요한 경우 |
| 핵심 특징 | **단일 주소 공간**·단일 버스 공유 | 명령어·데이터 메모리·버스 **물리적 분리** | 주기억 통합·**L1 캐시** 분리 |
| 한계 | 공유 버스 경합에 따른 **대역폭 제한** | 분리 메모리의 **잔여 공간** 전용 고정 | 명령어·데이터 캐시 간 **일관성** 유지 부담 |

> 요약: 하버드의 **공간 고정**을 주기억 통합으로 해소한 수정 하버드

### 쉽게 이해하기 (학습용)
- 폰 노이만 구조는 명령어와 데이터가 한 길을 다퉈 대역폭이 제한되고, 하버드 구조는 길을 나눠 동시 접근을 얻는 대신 한쪽 메모리의 빈 공간을 다른 쪽에 쓰기 어렵기 때문에, 수정 하버드는 큰 주기억장치는 합치고 코어 앞 캐시만 나눠 두 조건을 절충한다.

## Ⅵ. 실무 사례

1. 범용 CPU에서 주기억은 통합하고 **L1 캐시**는 분리

### 쉽게 이해하기 (학습용)
- 범용 CPU는 주기억장치를 통합하되 코어의 L1 캐시를 명령어 캐시와 데이터 캐시로 분리하여 두 경로에 동시에 접근한다.

## Ⅶ. 결론

- 용량 유연성과 동시 접근 요구에 맞춰 **메모리 구조** 선택

### 쉽게 이해하기 (학습용)
- 범용 시스템은 메모리 활용성이 높은 수정 하버드 구조를 적용하고, 결정적 처리량이 중요한 신호 처리 장비는 명령·데이터 경로를 완전히 분리한 하버드 구조를 적용한다.
