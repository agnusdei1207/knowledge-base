## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **폰 노이만 아키텍처(Von Neumann Architecture)**: CPU와 단일 주기억장치 간에 단일 시스템 버스를 공유하여 명령어 인출과 데이터 접근을 시분할 순차 처리하는 컴퓨터 구조.
- **하버드 아키텍처(Harvard Architecture)**: 명령어 메모리/버스와 데이터 메모리/버스를 물리적으로 완전 분리하여 동시 병렬 접근을 지원하는 컴퓨터 구조.

</details>

- 정의/개념: CPU와 주기억장치 간 버스 및 메모리 공간을 공유하는 **폰 노이만 아키텍처**와 물리적 전용 경로로 분리하는 **하버드 아키텍처**로 구분되는 프로세서-메모리 연결 구조
- 배경/필요성: 단일 **공유 버스**에서는 명령어 인출과 데이터 접근이 매 사이클 같은 선로를 두고 경합해 한쪽이 반드시 대기 비용을 치르므로, 두 트래픽의 경로를 물리적으로 분리한 전용 버스를 두어 동일 사이클에 양측을 동시 인출할 구조의 필요

#### 한줄 요약
- 폰 노이만은 단일 공유 버스를 통해 공간 유연성을 확보하고, 하버드는 물리적으로 분리된 전용 버스를 통해 동시 접근 성능을 극대화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수정 하버드 아키텍처(Modified Harvard Architecture)**: 프로세서 코어 내부(L1 캐시)에서는 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)를 분리하고, 외부 하위 메모리는 단일 통합 공간으로 공유하는 절충형 구조.
- **폰 노이만 병목(Von Neumann Bottleneck)**: 명령어 인출과 데이터 읽기/쓰기가 단일 시스템 버스의 대역폭을 공유함에 따라 CPU 고속 연산 성능이 버스 전송 속도에 제약되는 현상.
- **명령어 인출(Instruction Fetch)**: 프로그램 카운터(PC)가 가리키는 주소에서 실행할 명령어를 CPU 내부 레지스터로 읽어오는 파이프라인 첫 단계.

</details>

- 폰 노이만 구조: 단일 버스 공유에 따른 **폰 노이만 병목**으로 인해 명령어 인출과 데이터 접근이 순차적으로 직렬화
- 하버드 구조: 물리적 분리 버스를 통해 명령어 인출과 데이터 읽기/쓰기의 동시 처리를 지원하여 **명령어 대역폭** 극대화
- 수정 하버드 구조: 코어 내부 L1 캐시만 **I-Cache와 D-Cache**로 분리하고 하위 메모리는 통합 공유하여 성능과 저장 효율의 절충 달성

#### 한줄 요약
- 공유 버스는 저장 공간 유연성이 높지만 직렬화 병목이 발생하고, 분리 버스는 동시 처리 속도가 빠르지만 회로 복잡도가 증가하는 상충 관계를 갖는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 캐시(Instruction Cache, I-Cache)**: CPU 코어 내부에 위치하여 명령어 인출 전용 대역폭을 제공하고 데이터 접근과의 버스 경합을 차단하는 고속 캐시.
- **데이터 캐시(Data Cache, D-Cache)**: CPU 코어 내부에 위치하여 데이터 읽기/쓰기 전용 대역폭을 제공하는 고속 캐시.
- **통합 메모리(Unified Memory)**: 프로그램 코드와 실행 데이터가 동일한 물리적 주소 공간과 메모리 채널을 공유하는 단일 주기억장치(DRAM) 계층.

</details>

```text
프로세서-메모리 연결 구조
|
+-- 폰 노이만
|   `-- [CPU] -- [공유 버스] -- [통합 메모리]
|
+-- 하버드
|   +-- [CPU] -- [명령어 버스] -- [명령어 메모리]
|   `-- [CPU] -- [데이터 버스] -- [데이터 메모리]
|
`-- 수정 하버드
    +-- [CPU] -- [I-Cache]
    +-- [CPU] -- [D-Cache]
    `-- [공유 버스] -- [통합 메모리]
```

선의 의미: 가지는 포함, 가로선은 정적 연결 관계

| 구성요소 | 책임 |
|:---|:---|
| 통합 메모리·공유 버스 | 명령어와 데이터를 한 **주소 공간**에서 순차 전송 |
| 분리 메모리·전용 버스 | 코드와 데이터의 **독립 대역폭** 보장 |
| 분리 L1 캐시·통합 메모리 | 내부 **I/D 캐시**와 외부 공유 공간의 계층화 |

#### 한줄 요약
- 현대 CPU는 코어 내부에서는 하버드 방식으로 동시 접근 대역폭을 확보하고, 외부 메모리는 폰 노이만 방식으로 공간 유연성을 확보하는 수정 하버드 구조를 사용한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 유지보수(Cache Maintenance)**: I-Cache와 D-Cache 간 데이터 불일치를 방지하기 위해 캐시 플러시(Flush) 및 무효화(Invalidate)를 수행하는 일관성 제어 동작.
- **자기 수정 코드(Self-Modifying Code)**: 실행 중 데이터 영역에서 동적으로 생성하거나 수정한 기계어 코드를 메모리에 기록한 후 즉시 실행하는 코드 패턴.

</details>

```text
CPU 파이프라인의 메모리 참조 요구 (명령어 인출 / 데이터 접근)
                      │
                      ▼
         1. 아키텍처 버스 경로 판정
           ┌──────────┴──────────┐
      [ 폰 노이만 ]          [ 하버드 / 수정 하버드 ]
           │                      │
           ▼                      ▼
  단일 공유 버스 경합      2. 분리 경로 동시 접근
  (시분할 순차 접근)              │
           │               ┌──────┴──────┐
           │             적중           미스
           │               │             │
           ▼               ▼             ▼
     접근 지연 발생     동시 완료    통합 메모리 계층 순회
```

분기 결과: **폰 노이만**은 접근 직렬화, **수정 하버드**는 L1 적중 시 병렬 처리

**동작 원리**

1. **아키텍처 버스 경로 판정**: 공유·분리 경로에 따라 접근 직렬화 여부 결정
2. **분리 경로 동시 접근**: I/D 캐시를 병렬 조회해 적중 시 동시 완료

#### 한줄 요약
- 메모리 참조 요구 발생 시 수정 하버드 구조는 L1 I/D 분리 캐시를 통해 동시 접근을 지원하며, 미스 시에만 하위 통합 메모리로 내려간다.

## Ⅴ. 종류 및 비교

| 컴퓨터 아키텍처 | 폰 노이만 아키텍처 | 수정 하버드 아키텍처 | 하버드 아키텍처 |
|:---|:---|:---|:---|
| 적용 기준 | 단순한 통합 메모리 시스템 | 범용 프로세서와 운영체제 | 고정 신호 처리와 전용 제어기 |
| 핵심 특징 | 단일 **통합 메모리** 및 단일 **공유 버스** | 코어 내부 **분리 I/D 캐시** 및 외부 통합 메모리 | 물리적 **완전 분리** 코드·데이터 메모리 및 전용 버스 |
| 한계 | 공유 버스 경합으로 **파이프라인 스톨** 증가 | 자기 수정 코드의 **캐시 유지보수** 비용 | 코드·데이터 용량 고정으로 **공간 유연성** 저하 |
| 동시 접근성 | 단일 버스에서 순차 접근 | L1 캐시 적중 시 동시 접근 | 분리 버스에서 동시 접근 |

#### 한줄 요약
- 단순 제어에는 폰 노이만, 고정 신호 처리에는 하버드가 적합하며, 범용 OS 컴퓨팅에는 캐시 계층을 절충한 수정 하버드가 최적의 선택이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **직접 메모리 접근(Direct Memory Access, DMA)**: CPU 개입 없이 주변장치가 주기억장치에 고속으로 데이터를 직접 전송하는 하드웨어 제어 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 버스 공유 시 명령어 인출과 데이터 접근 간 파이프라인 지연 | **I-Cache·D-Cache** 계층 분리 적용 | 코어 레벨 폰 노이만 병목 완화 및 파이프라인 효율 극대화 |
| DMA가 D-Cache를 거치지 않고 메모리를 갱신하여 데이터 불일치 발생 | **D-Cache Flush** 및 **무효화** 수행 | 메모리-캐시 간 데이터 일관성 보장 |
| 자기 수정 코드(JIT 등) 실행 시 I-Cache의 과거 명령어 오실행 위험 | **D-Cache Clean** 및 **I-Cache Invalidate** 동기화 수행 | 런타임 생성 기계어의 정확한 인출 및 일관성 확보 |

#### 한줄 요약
- 수정 하버드 아키텍처 채택 시 고속 병렬 처리가 가능해지나, DMA 및 동적 코드 생성 환경에서는 I/D 캐시 간 일관성 유지보수 설계가 필수적이다.

## Ⅶ. 결론

- 범용 처리는 **수정 하버드**, 고정 신호 처리는 **하버드** 선택

#### 한줄 요약
- 폰 노이만의 공간 유연성과 하버드의 동시 대역폭 성능을 절충한 수정 하버드 아키텍처가 현대 프로세서의 표준이며, 캐시 일관성 관리가 실무 설계의 핵심이다.
