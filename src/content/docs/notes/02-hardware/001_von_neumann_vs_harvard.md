## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **폰 노이만 구조** 는 명령어와 데이터가 하나의 메모리와 버스를 공유하는 컴퓨터 구조이다.
- **하버드 구조** 는 명령어와 데이터의 메모리 및 버스를 분리하여 두 접근을 동시에 처리하는 컴퓨터 구조이다.
- **컴퓨터 아키텍처** 는 프로세서와 메모리 및 입출력 경로의 구성과 동작 규칙을 정의한 구조이다.
- **동시 접근 병목** 은 명령어 인출과 데이터 접근이 같은 경로를 두고 경쟁하여 대기가 발생하는 현상이다.

</details>

- 정의/개념: **폰 노이만 구조와 하버드 구조** 는 명령어와 데이터의 메모리•버스를 각각 공유하거나 분리하는 **컴퓨터 아키텍처**
- 배경/필요성: 단일 공유 경로에서는 명령어 인출과 데이터 접근이 경쟁해 **동시 접근 병목이 발생**

#### 한줄 요약
- 폰 노이만 구조는 명령어와 데이터가 같은 경로를 공유해 접근이 겹치면 대기하고, 하버드 구조는 경로를 분리해 동시 접근한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **주소 공간** 은 프로세서가 명령어나 데이터를 식별하여 접근할 수 있는 메모리 주소의 전체 범위이다.
- **수정 하버드 구조** 는 주기억장치를 통합하되 L1 명령 캐시와 데이터 캐시를 분리하여 용량 유연성과 동시 접근을 함께 확보한다.
- **명령어•데이터 동시 접근** 은 서로 분리된 경로에서 명령어 인출과 데이터 읽기•쓰기를 같은 시점에 수행하는 방식이다.
- **메모리 용량 배분** 은 명령어와 데이터가 사용할 저장 공간의 크기를 필요에 따라 나누는 작업이다.
- **주기억 통합•L1 캐시 분리** 는 하나의 주기억장치를 공유하면서 코어 가까이의 명령 캐시와 데이터 캐시만 나누는 구조이다.

</details>

- 경로를 분리하면 **명령어•데이터 동시 접근** 가능
- 주소 공간을 통합하면 **메모리 용량 배분** 유연성 확보
- **주기억 통합•L1 캐시 분리** 로 용량 유연성과 동시 접근 확보

#### 한줄 요약
- 두 구조의 판단축은 명령어•데이터의 메모리와 버스를 통합할지 분리할지이며, 버스 분리는 동시 접근 성능을 높이고 메모리 통합은 공간 활용과 설계를 단순화한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **CPU** 는 명령어를 인출•해독하고 데이터를 연산하며 메모리 접근 요청을 생성하는 장치이다.
- **버스** 는 CPU와 메모리 및 입출력장치 사이에서 주소•데이터•제어 신호를 전달하는 전송 통로이다.
- **경로 제어기** 는 구조에 따라 명령어와 데이터 요청을 공유 또는 분리 버스에 배치하는 제어부이다.
- **명령어•데이터 전용 경로** 는 각 접근에 별도 메모리와 버스를 제공하는 하버드 구조의 통로이다.

</details>

```mermaid
block
    columns 3
    C["CPU"] --- P["경로 제어기"]
    P --- I["명령어 메모리•버스"]
    P --- D["데이터 메모리•버스"]
    P --- M["통합 메모리•버스"]
```

| 구성요소 | 책임 |
|:---|:---|
| CPU | 명령어 인출•데이터 읽기•쓰기 **요청 생성** |
| 경로 제어기 | 구조별 **버스 접근 순서** 결정 |
| 명령어 메모리•버스 | 하버드의 **명령어 전용 경로** 제공 |
| 데이터 메모리•버스 | 하버드의 **데이터 전용 경로** 제공 |
| 통합 메모리•버스 | 폰 노이만의 **공유 경로** 제공 |

#### 한줄 요약
- CPU와 제어기가 요청을 배치하고 통합 또는 분리된 메모리 경로가 명령어와 데이터를 전달한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **공유 경로** 는 명령어와 데이터가 같은 메모리•버스를 사용하여 접근 순서를 나눠 갖는 통로이다.
- **폰 노이만•하버드 경로** 는 명령어와 데이터를 한 통로에서 순차 처리하거나 두 통로에서 병렬 처리하는 방식이다.

</details>

```mermaid
sequenceDiagram
    participant C as CPU
    participant I as 명령어 메모리•버스
    participant D as 데이터 메모리•버스
    participant M as 통합 메모리•버스
    alt 폰 노이만 통합 경로
        C->>M: 1. 명령어•데이터 순차 요청
        M-->>C: 명령어•데이터 반환
    else 하버드 분리 경로
        par 명령어 인출
            C->>I: 1. 명령어 요청
            I-->>C: 명령어 반환
        and 데이터 접근
            C->>D: 1. 데이터 요청
            D-->>C: 데이터 반환
        end
    end
```

**동작 원리**

- **1. 경로별 접근 요청**: 폰 노이만은 공유 경로를 순차 사용하고 하버드는 분리 경로를 병렬 사용

#### 한줄 요약
- 폰 노이만 구조는 한 통로의 사용 순서를 조정하고, 하버드 구조는 명령어와 데이터를 서로 다른 통로로 동시에 전달한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단일 주소 공간** 은 명령어와 데이터가 같은 주소 체계를 사용하므로 메모리 용량을 유연하게 배분할 수 있게 한다.
- **L1 캐시** 는 CPU 코어에 가장 가까운 소용량 고속 캐시이며, 수정 하버드 구조에서는 명령 캐시와 데이터 캐시로 나뉜다.
- **실시간 신호 처리** 는 정해진 시간 안에 연속 신호 데이터를 처리해야 하는 작업이다.
- **ISA(Instruction Set Architecture)** 는 프로세서가 실행할 명령어와 레지스터•메모리 동작을 정의한 규격이다.
- **대역폭 제한** 은 공유 버스가 단위 시간에 전달할 수 있는 데이터양 때문에 성능이 제한되는 상태이다.
- **캐시 일관성** 은 명령 캐시와 데이터 캐시가 같은 메모리 주소의 변경을 일치되게 반영하는 성질이다.

</details>

| 컴퓨터 구조 | 폰 노이만 구조 | 하버드 구조 | 수정 하버드 구조 |
|:---|:---|:---|:---|
| 적용 기준 | 명령어•데이터 **용량 비율** 이 변하는 경우 | **실시간 신호 처리** 에 동시 접근이 필요한 경우 | 범용 ISA에 **고속 인출** 이 필요한 경우 |
| 핵심 특징 | **단일 주소 공간**•단일 버스 공유 | 명령어•데이터 메모리•버스 **물리적 분리** | 주기억 통합•**L1 캐시** 분리 |
| 한계 | 공유 버스 경합에 따른 **대역폭 제한** | 분리 메모리의 **잔여 공간** 전용 고정 | 명령어•데이터 캐시 간 **일관성** 유지 부담 |

> 요약: 하버드의 **공간 고정** 을 주기억 통합으로 해소한 수정 하버드

#### 한줄 요약
- 폰 노이만은 한 경로를 공유하고 하버드는 두 경로를 분리하며, 수정 하버드는 주기억을 합치고 L1 캐시만 나눠 절충한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **폰 노이만 병목** 은 명령어와 데이터가 단일 버스를 공유하여 메모리 전송 대기가 CPU 성능을 제한하는 현상이다.
- **캐시 일관성** 은 여러 캐시가 같은 메모리 주소에 대해 일치하는 값을 유지하도록 보장하는 성질이다.
- **명령 캐시 무효화** 는 DMA나 코드 변경 뒤 캐시에 남은 오래된 명령어 사본을 제거하여 실행 정확성을 보장하는 절차이다.
- **프리페치(Prefetch)** 는 곧 사용할 명령어나 데이터를 미리 캐시에 가져오는 처리이다.
- **버스 대역폭** 은 버스가 단위 시간에 전송할 수 있는 데이터양이다.
- **DMA(Direct Memory Access)** 는 CPU를 거치지 않고 장치와 메모리 사이에서 데이터를 전송하는 방식이다.
- **캐시 적중률•대기 주기** 는 요청값을 캐시에서 찾은 비율과 버스나 메모리를 기다린 클록 주기 수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 명령어•데이터의 **공유 버스 경합으로 CPU 대기** | 캐시•프리페치•**버스 대역폭** 확대 | **폰 노이만 병목** 완화 |
| 수정 하버드 캐시의 **코드•데이터 불일치** | 캐시 일관성•**명령 캐시 무효화** 절차 적용 | 자기 수정 코드•**DMA 정확성** 확보 |
| 분리 메모리 한쪽의 **용량 부족•잔여 공간 고정** | 수정 하버드•**재배치 가능한 메모리** 구성 | **메모리 용량 활용성** 향상 |
| 이론적 동시 접근에도 **실제 처리량이 개선되지 않음** | 캐시 적중률•버스 사용률•**대기 주기** 측정 | **실제 병목 위치** 식별 |
| 범용 CPU의 **인출•데이터 접근 동시성 요구** | 주기억 통합•**L1 명령어/데이터 캐시 분리** | 용량 유연성과 **고속 동시 접근** 절충 |

#### 한줄 요약
- 분리 구조를 선택한 뒤에도 캐시 적중률과 버스 대기 시간을 측정해야 실제 처리량 이득을 확인할 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **DSP** 는 반복적인 신호 연산을 빠르게 처리하기 위해 명령어와 데이터 경로를 분리해 사용하는 전용 프로세서이다.
- **수정 하버드 구조** 는 주기억은 통합하고 L1 명령 캐시와 데이터 캐시는 분리한 구조이다.
- **결정적 처리량** 은 실행 조건이 같을 때 정해진 시간마다 일정한 작업량을 보장하는 성질이다.

</details>

- 범용은 **수정 하버드**, 결정적 처리량은 **하버드** 선택

#### 한줄 요약
- 범용 시스템은 메모리 활용성이 높은 수정 하버드 구조를 적용하고, 결정적 처리량이 중요한 신호 처리 장비는 명령•데이터 경로를 완전히 분리한 하버드 구조를 적용한다.
