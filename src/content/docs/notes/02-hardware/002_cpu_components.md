## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령어를 인출•해독•실행하고 결과를 기록하는 처리 장치이다.

</details>

- 정의/개념: **CPU**는 ALU•제어장치•레지스터•버스가 명령어의 인출•해독•실행•기록을 분담하는 처리 장치이다.
- 배경/필요성: 명령을 정확히 실행하려면 연산•상태 보관•제어•데이터 전송 책임을 각각 맡는 구성요소가 필요하다.

#### 한줄 요약
- Control Path(CU)의 Instruction Fetch-Decode와 Data Path(ALU, Register File, Bus)의 Execute-Writeback 구분을 통해 파이프라인 제어를 다룬다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **제어 경로**: 명령어 해독 결과에 따라 데이터 경로의 동작 순서와 제어 신호를 결정하는 회로이다.
- **데이터 경로**: 레지스터•산술논리장치•버스를 연결하여 피연산자와 결과를 이동시키는 회로이다.
- **레지스터**: 중앙처리장치 내부에서 피연산자•주소•상태•중간 결과를 보관하는 고속 저장장치이다.
- **클록 엣지**: 순차 회로가 입력을 받아 내부 상태를 갱신하는 클록 신호의 변화 시점이다.

</details>

- **제어 경로** 해독 신호로 **데이터 경로**의 연산·전송을 선택한다.
- 피연산자·주소·상태를 보관하는 **레지스터** 중심 연산이 핵심이다.
- **클록 엣지**마다 연산 결과로 레지스터 상태를 동기 갱신한다.

#### 한줄 요약
- Control Unit의 Control Signals 생성에 의하여 Data Path의 MUX/ALU 연산이 선택되고, Clock Edge(Rising/Falling) 시점에 Flip-Flop 레지스터 상태가 동기화 갱신된다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **산술논리장치(Arithmetic Logic Unit, ALU)**: 레지스터가 제공한 피연산자에 산술•논리•시프트 연산을 수행하는 장치이다.
- **제어장치(Control Unit, CU)**: 명령어를 해독하여 데이터 경로의 동작 순서와 제어 신호를 생성하는 장치이다.
- **레지스터 파일**: 여러 범용 레지스터를 묶어 피연산자를 읽고 연산 결과를 기록하는 저장 구조이다.
- **특수 목적 레지스터**: 프로그램 카운터•명령어 레지스터•상태 레지스터처럼 정해진 제어 상태를 보관하는 레지스터이다.
- **내부 버스**: 레지스터와 산술논리장치 사이에서 피연산자와 연산 결과를 전달하는 통로이다.
- **제어 신호**: 데이터 경로의 읽기•연산•쓰기를 선택하고 활성화하는 전기적 신호이다.

</details>

```text
CPU
├─ 제어 경로
│  ├─ 제어장치
│  └─ 특수 목적 레지스터
└─ 데이터 경로
   ├─ 레지스터 파일
   ├─ 산술논리장치
   └─ 내부 버스
```

가지의 의미: CPU 내부의 제어 경로와 데이터 경로별 정적 구성이다.

| 구성요소 | 책임 |
|:---|:---|
| **CU** | 명령어 해독과 **제어 신호** 생성 |
| **레지스터 파일** | 피연산자 읽기와 연산 결과 기록 |
| **특수 목적 레지스터** | 명령어 주소•현재 명령•상태 비트 보관 |
| **ALU** | 산술•논리•시프트 연산 수행 |
| **내부 버스** | 레지스터•ALU 사이 피연산자와 결과 전송 |

#### 한줄 요약
- Control Path(CU, PC, IR)가 제어 타이밍을 통제하고, Data Path(GPR, ALU, Internal Bus)가 피연산자 연산 및 데이터 래칭을 수행한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 메모리 주소를 저장하는 레지스터이다.
- **명령어 레지스터(Instruction Register, IR)**: 현재 인출한 명령어를 보관하여 제어장치가 해독할 수 있게 하는 레지스터이다.
- **상태 비트**: 연산 결과의 0•부호•캐리•오버플로 여부를 나타내는 값이다.
- **명령어 인출**: PC가 가리킨 메모리 주소에서 명령어를 읽어 IR에 저장하는 단계이다.
- **명령어 해독**: 명령어의 연산 종류•피연산자 위치•결과 목적지를 판정하는 단계이다.
- **피연산자 읽기**: 명령어가 지정한 레지스터에서 연산 입력값을 가져오는 단계이다.
- **연산 실행**: ALU가 선택한 산술•논리•시프트 연산을 수행하는 단계이다.
- **결과 기록**: 연산 결과와 상태 비트를 목적 레지스터에 저장하는 단계이다.

</details>

```text
프로그램 카운터의 명령어 주소
              │
              ▼
       1. 명령어 인출
              │
              ▼
       2. 명령어 해독
              │
              ▼
       3. 피연산자 읽기
              │
              ▼
         4. 연산 실행
              │
              ▼
         5. 결과 기록
              │
              ▼
     레지스터•상태 비트 갱신
```

### 동작 원리

1. **명령어 인출**: **PC** 주소의 명령어를 **IR**에 저장한다.
2. **명령어 해독**: 제어장치가 연산 종류•피연산자 위치•결과 목적지를 판정한다.
3. **피연산자 읽기**: 명령어가 지정한 **레지스터 파일**에서 입력값을 선택한다.
4. **연산 실행**: 선택한 피연산자에 **ALU** 연산을 수행한다.
5. **결과 기록**: 연산 결과를 목적 레지스터에 쓰고 **상태 비트**를 갱신한다.

#### 한줄 요약
- PC $\rightarrow$ MAR $\rightarrow$ Memory Read $\rightarrow$ MDR $\rightarrow$ IR Fetch 과정을 거쳐 CU Decoder $\rightarrow$ ALU Execution $\rightarrow$ Register Writeback 순서로 수행된다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **범용 레지스터(General-Purpose Register, GPR)**: 피연산자•주소•중간 결과를 명령어가 비교적 자유롭게 지정하여 사용하는 레지스터이다.
- **스택 포인터(Stack Pointer, SP)**: 현재 스택 최상단의 주소를 보관하는 특수 목적 레지스터이다.
- **상태 레지스터(Status Register)**: 연산 결과와 제어 상태를 나타내는 조건 비트를 보관하는 특수 목적 레지스터이다.
- **제어 레지스터**: 명령어 실행 순서와 프로세서 제어 상태를 보관하는 특수 목적 레지스터 유형이다.
- **주소 레지스터**: 메모리나 스택 위치를 가리키는 주소를 보관하는 레지스터 유형이다.

</details>

| 레지스터 유형 | 대표 레지스터 | 저장 정보 | 처리 역할 |
|:---|:---|:---|:---|
| **GPR** | 정수•주소 레지스터 | 피연산자•중간 결과 | 명령어의 연산 값 공급 |
| **제어 레지스터** | **PC**•**IR** | 다음 주소•현재 명령 | 명령어 인출•해독 순서 유지 |
| **주소 레지스터** | **SP** | 스택 최상단 주소 | 호출 프레임•지역 데이터 위치 추적 |
| **상태 레지스터** | 플래그 레지스터 | 0•부호•캐리•오버플로 | 조건 분기와 예외의 판정 근거 |

#### 한줄 요약
- GPR은 피연산자/중간 연산값, Control/Status Register(PC, IR, PSR, SP)는 CPU의 Execution State 및 Control Flow 트래킹을 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **다중 포트 레지스터 파일**: 같은 클록 주기에 여러 피연산자를 동시에 읽거나 쓸 수 있도록 복수 포트를 둔 레지스터 파일이다.
- **데이터 해저드(Data Hazard)**: 앞 명령어의 결과가 준비되기 전에 뒤 명령어가 그 값을 사용하려 하여 발생하는 의존성 충돌이다.
- **포워딩(Forwarding)**: 연산 결과를 레지스터 기록까지 기다리지 않고 의존 명령어의 입력으로 직접 전달하는 기법이다.
- **파이프라인 인터록(Pipeline Interlock)**: 필요한 피연산자가 준비될 때까지 의존 명령어의 진행을 정지하는 제어 회로이다.
- **버스 경합**: 여러 구성요소가 같은 버스를 동시에 사용하려 하여 전송 충돌이나 대기가 발생하는 현상이다.
- **버스 중재(Bus Arbitration)**: 여러 전송 요청 가운데 한 요청에 버스 사용 권한을 부여하는 절차이다.
- **제어 신호 타이밍**: 레지스터 읽기•연산•쓰기 신호가 데이터 경로 지연에 맞춰 유효해지는 시점이다.
- **레지스터 포트**: 레지스터 파일에서 값을 읽거나 쓰는 독립 접근 통로이다.
- **설정•유지 시간**: 클록 엣지 전후로 레지스터 입력이 안정적으로 유지되어야 하는 최소 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동시 피연산자 접근에 따른 **레지스터 포트** 충돌 | **다중 포트 레지스터 파일** 구성 | 병렬 피연산자 공급 대기 감소 |
| 선행 결과 미기록에 따른 **데이터 해저드** | **포워딩**•**파이프라인 인터록** 적용 | 의존 명령에 정확한 피연산자 공급 |
| 공유 전송 경로의 동시 요청에 따른 **버스 경합** | 고정•순환 우선순위 **버스 중재** | 전송 충돌 방지 |
| 데이터 경로 지연과 불일치한 **제어 신호 타이밍** | 최악 경로 기준 클록•제어 논리 검증 | **설정•유지 시간** 충족 |

#### 한줄 요약
- Multi-ported Register File, Forwarding Unit, Pipeline Hazard Detection/Interlock, Bus Arbiter 기법으로 Data Hazard 및 Bus Contention을 예방한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 명령어 형식•레지스터•주소 지정 방식처럼 소프트웨어에 보이는 프로세서 실행 규약이다.
- **CPU 구성 설계 기준**: ISA의 피연산자 수와 데이터 폭에 맞춰 레지스터 파일과 데이터 경로를 정하는 기준이다.

</details>

- **CPU 구성 설계 기준**에 따라 **ISA**의 피연산자 수•폭에 맞춘 **레지스터 파일**과 **데이터 경로**를 설계한다.

#### 한줄 요약
- ISA 사양(Register Bit Width, Operand Code Field)에 맞추어 Register File Read/Write Port 수 및 Data Path Multiplexer/ALU Bit-width를 통합 설계한다.
