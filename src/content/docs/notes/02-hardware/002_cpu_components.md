## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 인출·해독·실행하고 컴퓨터 전체 시스템의 데이터 흐름과 동작을 제어하는 핵심 하드웨어 장치.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 제어장치의 지시에 따라 산술 연산, 논리 연산, 비트 시프트 및 조건 비교를 수행하는 CPU 내부 핵심 실행 회로.
- **제어장치(Control Unit, CU)**: 메모리에서 인출한 명령어를 해독하여 ALU, 레지스터, 버스의 동작 타이밍과 데이터 전송을 지휘하는 마이크로 제어 신호 발생 장치.
- **레지스터(Register)**: CPU 내부 데이터패스에 위치하여 명령어, 데이터 주소, 피연산자 및 상태 플래그를 1클록 내에 초고속으로 저장·제공하는 임시 기억소자.
- **내부 버스(Internal Bus)**: CPU 내부 구성요소 간에 주소, 데이터, 제어 신호를 상호 교환하기 위한 공통 신호 전송 선로.

</details>

- 정의/개념: 연산(ALU)·제어(CU)·저장(레지스터)·전송(내부 버스)의 네 핵심 하드웨어 유닛이 유기적으로 협력하여 명령어 사이클을 완결하는 **CPU** 내부 마이크로아키텍처 구조
- 배경/필요성: 단일 통합 회로의 제어 복잡도를 낮추고 명령어 실행 단계별 독립적인 파이프라인 하드웨어 모듈화 달성

#### 한줄 요약
- CPU는 연산(ALU), 지휘(CU), 고속 저장(레지스터), 연결 통로(버스)의 네 책임이 분리되어 1클록 단위로 맞물려 돌아가는 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터패스(Datapath)**: ALU, 레지스터 파일, 내부 버스 등 실제 연산 수행과 피연산자 데이터의 이동이 일어나는 하드웨어 실행 경로.
- **제어 신호(Control Signal)**: CU가 매 사이클마다 레지스터 쓰기 인에이블, ALU 연산자 선택, 멀티플렉서 분기 등을 지시하는 전압 신호.
- **프로그램 카운터(Program Counter, PC)**: 다음에 실행할 명령어의 메모리 주소를 보관하며, 순차 인출 시 자동 증가하고 분기 시 대상 주소로 갱신되는 특수 레지스터.

</details>

- 제어와 실행 분리: CU의 **제어 신호** 생성과 **데이터패스**의 실행이 분리되어 단일 하드웨어로 다양한 기계어 명령어를 유연하게 처리
- 초고속 데이터 공급: ALU와 레지스터 파일이 직접 연결되어 피연산자 인출부터 연산 결과 저장까지 1클록 내 완결
- 공통 버스 공유: **내부 버스**를 통해 구성요소 간 연결선 수를 절감하되, 동시 전송 불가에 따른 버스 경합을 중재 회로로 통제

#### 한줄 요약
- 제어장치가 지휘 신호를 만들고 데이터패스가 연산을 수행하는 구조적 분리를 통해 범용성과 고속 처리 능력을 동시에 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 레지스터(Instruction Register, IR)**: 메모리에서 인출된 현재 실행 대상 명령어를 해독 완료 시까지 임시 보관하는 레지스터.
- **명령어 디코더(Instruction Decoder)**: IR의 Opcode 필드를 해석하여 해당 명령어에 대응하는 세부 마이크로 연산 제어 신호를 생성하는 논리 회로.
- **상태 플래그 레지스터(Status/Flags Register)**: ALU 연산 결과에 따라 Zero, Carry, Overflow, Sign 등의 상태 비트를 저장하여 조건부 분기 판정을 지원하는 레지스터.

</details>

```text
[CPU 하드웨어 패키지]
 ├─ [제어장치 (Control Unit)]
 │   ├─ 명령어 레지스터 (IR)
 │   ├─ 명령어 디코더 (Instruction Decoder)
 │   └─ 제어 타이밍 신호 발생기
 │
 ├─ [데이터패스 (Datapath)]
 │   ├─ 산술논리연산장치 (ALU)
 │   ├─ 범용 레지스터 파일 (General-Purpose Registers)
 │   ├─ 프로그램 카운터 (PC)
 │   └─ 상태 플래그 레지스터 (Status Register)
 │
 └─ [내부 시스템 버스 (Internal Bus)]
     ├─ 주소 버스 (Address Bus)
     ├─ 데이터 버스 (Data Bus)
     └─ 제어 버스 (Control Bus)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 내부 시스템 버스는 CPU 외부의 시스템 버스 및 메모리 인터페이스와 연결됨

| 계층/유닛 | 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **제어 계층 (CU)** | IR, 디코더, 제어 회로 | 명령어 해독 및 각 하드웨어 장치로 **제어 신호** 분배 | 상태 머신 기반 실행 통제 |
| **연산 계층 (ALU)** | 가산기, 논리 연산기, 시프터 | 산술·논리·비교 연산 수행 및 상태 플래그 생성 | 단일 사이클 고속 조합 논리 |
| **저장 계층 (레지스터)** | PC, IR, 범용 레지스터, 플래그 | 명령어 주소, 피연산자, 중간 결과 및 상태 보관 | 1클록 내 다중 포트 읽기/쓰기 |
| **전송 계층 (내부 버스)** | 주소·데이터·제어 신호선 | 유닛 간 비트 전송 및 외부 메모리·I/O 인터페이스 연결 | 공통 전송로 공유 및 중재 |

#### 한줄 요약
- CPU 내부는 제어장치(CU), 실행 연산기(ALU), 저장소(레지스터), 연결망(버스)이 명확한 계층적 포함 관계를 형성하며 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 실행 주기(Instruction Cycle)**: 인출(Fetch) ➔ 해독(Decode) ➔ 실행(Execute) ➔ 저장(Write-Back)으로 이어지는 명령어 한 개의 처리 과정.

</details>

```text
1. 명령어 인출 (Fetch)
   - PC 주소를 주소 버스로 전달하여 메모리/캐시에서 명령어를 읽어 IR에 적재 (PC ← PC + 4)
       │
       ▼
2. 명령어 해독 (Decode)
   - CU 디코더가 IR의 Opcode와 피연산자를 해석하고 레지스터 파일에서 피연산자 인출
       │
       ▼
3. 명령어 실행 (Execute)
   - ALU가 제어 신호에 따라 연산 수행 또는 메모리 유효 주소 계산
       │
       ├─ 산술/논리 연산: ALU 결과 도출
       ├─ 메모리 접근 연산: 데이터 버스를 통해 메모리 읽기/쓰기 수행
       └─ 분기 연산: 조건 플래그 검증 후 PC를 목표 주소로 갱신
       │
       ▼
4. 결과 기록 (Write-Back)
   - 연산 결과 또는 메모리 로드 데이터를 목적 레지스터에 최종 반영
```

분기 결과: **산술·논리는** 레지스터 간 고속 처리로 완결되고, **메모리 연산은** 버스 접근 지연이 수반되며, **분기 연산은** PC 갱신을 통해 제어 흐름을 전환함

#### 한줄 요약
- 명령어 주기는 Fetch ➔ Decode ➔ Execute ➔ Write-Back의 4단계를 거치며, 각 단계마다 CU, ALU, 레지스터, 버스가 교대로 활성화된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 사이클 CPU(Single-Cycle CPU)**: 모든 명령어의 실행 주기를 단 1클록 안에 완료하도록 설계한 구조.
- **파이프라인 CPU(Pipelined CPU)**: 명령어 주기를 여러 단계로 분할하여 서로 다른 명령어를 각 단계에서 중첩 실행하는 구조.
- **슈퍼스칼라 CPU(Superscalar CPU)**: 파이프라인을 복수 개 병렬 배치하여 사이클당 2개 이상의 명령어를 동시 발행·실행하는 고성능 구조.

</details>

| 구현 방식 | 단일 사이클 CPU | 파이프라인 CPU | 슈퍼스칼라 / 비순서(OoO) CPU |
|:---|:---|:---|:---|
| 적용 기준 | 초소형 마이크로컨트롤러, 교육용 | 임베디드 코어, 표준 RISC 프로세서 | 고성능 서버, 데스크톱 범용 프로세서 |
| 핵심 특징 | **단일 데이터패스에 명령어당 1클록 고정** | **명령어 중첩 실행을 통한 처리량(CPI $\approx$ 1) 향상** | **복수 실행 유닛 병렬 배치 및 명령어 동적 재배치** |
| 한계 | 가장 긴 명령어(메모리 로드)에 클록 주기가 제약됨 | 데이터·구조·제어 해저드로 인한 파이프라인 스톨 | 회로 복잡도, 전력 소모 및 다이 면적 급증 |
| 하드웨어 비용 | 최소 회로 면적 및 단순한 CU | 파이프라인 레지스터 및 해저드 제어 회로 추가 | 리네이밍, 예약 스테이션, 재정렬 버퍼(ROB) 필수 |

#### 한줄 요약
- 단순 제어에는 단일 사이클이 적합하고, 표준 프로세서는 파이프라인을 쓰며, 극대화된 성능 요구에는 슈퍼스칼라 및 비순서 실행이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 후속 명령어가 선행 명령어의 레지스터 기록 완료 전 해당 값을 참조할 때 발생하는 데이터 의존성 충돌.
- **포워딩(Forwarding/Bypassing)**: 레지스터 쓰기(WB)를 기다리지 않고 ALU 출력 또는 메모리 버퍼 값을 후속 명령어의 실행(EX) 입력으로 직결하는 하드웨어 경로.
- **분기 예측(Branch Prediction)**: 조건부 분기 명령어의 분기 여부와 목적 주소를 사전에 예측하여 파이프라인 중단 없이 인출을 지속하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 선행 연산 결과 미기록 상태에서 후속 명령어가 레지스터 참조 시 오류 | **하드웨어 포워딩(Bypassing) 회로** 및 인터록 스톨 삽입 | 파이프라인 스톨 최소화 및 데이터 무결성 보장 |
| 조건부 분기 판정 지연으로 파이프라인 인출 중단 및 버블 발생 | **동적 분기 예측기(Branch Predictor)** 및 BTB 적용 | 제어 해저드 손실 최소화 및 연속 명령어 공급 |
| 복수 유닛의 동시 메모리 접근 요구로 버스 경합 발생 | **하버드/수정 하버드 L1 I/D 캐시 분리** 및 버스 중재기 구축 | 명령어 인출과 데이터 전송의 동시 처리 대역폭 확보 |

#### 한줄 요약
- CPU 성능 최적화는 하드웨어 유닛 간의 대기 시간을 줄이는 데 있으며, 포워딩, 분기 예측, 캐시 계층 분리가 필수적인 공학적 대책이다.

## Ⅶ. 결론

- 연산·제어·저장·전송의 책임을 독립된 하드웨어 유닛으로 분리하고, 요구 워크로드의 전력·면적·성능(PPA) 제약에 맞추어 **단일 사이클에서 파이프라인 및 슈퍼스칼라 비순서 마이크로아키텍처**로 확장 적용하며, **포워딩 및 분기 예측**을 결합하여 사이클당 명령어 처리율(IPC)을 극대화하는 프로세서 아키텍처 확립

#### 한줄 요약
- CPU는 CU, ALU, 레지스터, 버스의 유기적 분업 체계이며, 해저드를 통제하고 파이프라인을 병렬화함으로써 고성능 컴퓨팅을 구현한다.
