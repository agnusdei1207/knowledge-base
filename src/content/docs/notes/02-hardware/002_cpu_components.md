## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 인출·해석·실행하고 결과와 상태를 레지스터에 갱신하는 처리 장치.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 산술·논리·비교·시프트 연산을 수행하고 그 결과의 조건 코드까지 함께 내보내는 실행 회로.
- **제어장치(Control Unit, CU)**: 명령어를 해석해 ALU·레지스터·버스가 언제 무엇을 할지 지시하는 제어 신호를 발생시키는 순서 제어 회로.
- **레지스터(Register)**: CPU 내부에서 피연산자·주소·명령어·상태를 한 클록 안에 읽고 쓸 수 있도록 보관하는 고속 저장소.
- **버스(Bus)**: 주소·데이터·제어 신호를 여러 구성요소가 공유해 전달하는 전송 경로로, 한 시점에 한 전송만 허용되는 것이 특징.

</details>

- 정의/개념: 연산·제어·저장·전송의 네 책임을 분리한 구성요소가 협력해 명령어 한 개를 처리하는 **CPU** 내부 구조
- 배경/필요성: 명령어 실행에는 순서 결정·계산·중간값 보관·신호 전달이 모두 필요하며, 이를 한 회로에 뭉치면 검증과 교체가 불가능

#### 한줄 요약
- 네 구성요소는 기능을 나눈 결과가 아니라 서로의 대기 시간을 흡수하기 위해 나뉜 것이며, 그래서 하나가 느리면 나머지가 모두 멈춘다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 경로(Datapath)**: 피연산자와 연산 결과가 레지스터·ALU·메모리 사이를 오가는 회로 경로로, 폭과 단수가 곧 한 클록에 처리 가능한 일의 양을 결정.
- **제어 신호(Control Signal)**: CU가 레지스터 기록 여부·ALU 연산 종류·버스 방향을 매 클록 지시하는 신호로, 데이터 경로를 매번 다른 회로처럼 쓰게 만드는 수단.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어 주소를 보관하며 순차 실행에서는 자동 증가하고 분기에서는 목표 주소로 교체되는 레지스터.

</details>

- CU가 명령어를 해석해 **제어 신호**를 발생시키므로, 같은 **데이터 경로**가 명령어마다 다른 회로처럼 동작
- ALU와 레지스터가 데이터 경로를 이루어 피연산자 입력·연산·결과 보관을 한 클록 안에 연속 수행
- **버스**는 구성요소 간 결합도를 낮추는 대신 한 시점에 한 전송만 허용해 경합 지점이 됨

#### 한줄 요약
- 제어와 데이터를 분리한 덕분에 회로 하나로 모든 명령어를 처리할 수 있지만, 그 대가로 명령어마다 제어 신호를 새로 만들어야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 레지스터(Instruction Register, IR)**: 인출한 명령어 비트열을 CU가 해석을 마칠 때까지 붙잡아 두어, 메모리를 다시 읽지 않고도 해독을 진행하게 하는 레지스터.
- **명령어 디코더(Instruction Decoder)**: IR의 연산 코드와 피연산자 필드를 제어 신호 조합으로 변환하는 CU 내부 회로.
- **상태 레지스터(Status Register)**: ALU 연산이 남긴 영·음·올림수·오버플로 조건 코드를 보관해 이후 분기 명령의 판단 근거로 제공하는 레지스터.

</details>

```text
[CPU]
├─ CU
│  ├─ 명령어 디코더
│  └─ 제어 신호 발생기
├─ ALU
├─ 레지스터
│  ├─ PC
│  ├─ IR
│  └─ 상태 레지스터
└─ 버스 (주소·데이터·제어)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 버스만이 CPU 경계 밖 메모리·입출력과 이어지는 공유 전송 경로

| 구성요소 | 책임 |
|:---|:---|
| CU | **제어 신호** 발생으로 연산·전송 순서 결정 |
| ALU | 산술·논리·비교 연산 수행 및 조건 코드 출력 |
| PC | 다음 명령어 주소 보관·순차 증가·분기 시 교체 |
| IR | 인출 명령어 보관으로 해독 중 메모리 재접근 차단 |
| 상태 레지스터 | 조건 코드 보관으로 분기 판단 근거 제공 |
| 버스 | 주소·데이터·제어 신호 공유 전달 |

#### 한줄 요약
- 레지스터는 값을 빨리 읽으려고 두는 것이 아니라 단계 사이에서 값이 사라지지 않게 붙잡는 장치이며, 그래서 단계가 늘면 레지스터부터 늘어난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch)**: PC가 가리키는 주소에서 명령어를 버스로 읽어 IR에 적재하는 단계로, 모든 명령어가 예외 없이 거치는 공통 구간.
- **명령어 해독(Instruction Decode)**: CU가 IR의 연산 코드를 해석해 이후 단계에서 쓸 제어 신호를 확정하는 단계.
- **기록 단계(Write Back)**: 실행 결과를 목적 레지스터에 반영해 후속 명령어가 그 값을 볼 수 있게 만드는 최종 단계.

</details>

```text
PC 주소 → 버스 → 메모리
        │
   IR 적재 (명령어 인출)
        │
   명령어 해독: CU → 제어 신호 확정
        │
   연산 유형은 무엇인가?
 ┌──────┼─────────┐
산술·논리  메모리 접근    분기
 │        │          │
ALU 연산  주소 계산 후   조건 코드 판정
 │       버스 재사용     │
 │        │        ┌───┴───┐
 │        │      성립     미성립
 │        │        │        │
 └────┬───┘   PC ← 목표 주소  PC ← PC+4
      │
  기록 단계: 레지스터 갱신 후 PC 증가
```

분기 결과: 산술·논리는 ALU만 쓰고, 메모리 접근은 버스를 한 번 더 점유하며, 분기는 결과를 기록하는 대신 PC 자체를 교체

#### 한줄 요약
- 세 갈래가 쓰는 자원이 다르기 때문에 실행 단계의 소요 클록도 달라지며, 단일 사이클 설계가 가장 느린 갈래에 묶이는 이유가 여기에 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로아키텍처(Microarchitecture)**: 같은 ISA를 지키면서도 내부 구성요소를 몇 단으로 나누고 몇 개씩 둘지를 정하는 구현 방식으로, 성능 차이가 발생하는 실제 지점.
- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 프로그램이 관찰할 수 있는 명령어·레지스터·예외 동작의 규약으로, 구현이 바뀌어도 유지해야 하는 계약.

</details>

| CPU 구현 유형 | 단일 사이클 CPU | 파이프라인 CPU | 슈퍼스칼라·비순서 CPU |
|:---|:---|:---|:---|
| 적용 기준 | 초저전력 임베디드 제어기 | 범용 마이크로프로세서 | 고성능 서버·HPC 연산 |
| 핵심 특징 | 단일 데이터 경로에 하드와이어드 CU | 단계 분할로 명령어 중첩 실행 | 명령어를 동시에 해독하고 순서를 바꿔 실행 |
| 한계 | 클록 주기가 가장 긴 연산에 종속 | 의존성·자원 경합으로 스톨 발생 | 제어 회로 복잡도와 전력 소모 급증 |

#### 한줄 요약
- 세 구현은 같은 **ISA**를 지키므로 프로그램에는 동일하게 보이며, 차이는 전부 **마이크로아키텍처**가 감춘 병렬성의 양에서 나온다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 앞선 명령어의 결과가 기록 단계에 닿기 전에 후속 명령어가 그 값을 요구해 발생하는 의존성 충돌.
- **포워딩(Forwarding)**: 기록 단계를 기다리지 않고 ALU 출력을 후속 연산의 입력으로 직접 되돌려 의존성 대기를 없애는 기법.
- **파이프라인 플러시(Pipeline Flush)**: 잘못된 경로로 진입한 명령어를 파이프라인에서 제거해 올바른 실행 흐름으로 되돌리는 동작.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **데이터 해저드**로 후속 명령어가 오래된 값 참조 | **포워딩** 경로 추가와 불가피한 구간의 스톨 삽입 | 잘못된 피연산자 사용 차단 |
| 분기 판정 지연으로 잘못된 명령어가 이미 진입 | 분기 확정 시점에 **파이프라인 플러시** 수행 | 잘못된 실행 경로의 결과 기록 방지 |
| 인출과 데이터 접근이 **버스**를 동시에 요구해 전송 지연 | 버스 중재 규칙 수립과 명령어·데이터 경로 분리 | 공유 경로 대기 시간 감소 |

#### 한줄 요약
- 성능을 깎는 것은 연산 속도가 아니라 값이 준비되기를 기다리는 시간이며, 대책은 모두 그 대기를 없애거나 감추는 방향으로 모인다.

## Ⅶ. 결론

- 전력·처리량·제어 복잡도를 기준으로 저전력 제어기는 단일 사이클 구현, 범용·서버는 파이프라인 이상의 **마이크로아키텍처**를 선택하되 **ISA** 계약은 어느 쪽이든 동일하게 유지

#### 한줄 요약
- CPU 구성은 부품 이름을 외우는 문제가 아니라 제어·연산·저장·전달 책임을 어느 단위로 쪼개 대기 시간을 감출지 정하는 설계 문제이다.
