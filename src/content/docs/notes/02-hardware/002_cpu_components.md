## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 인출·해석·실행하고 결과와 상태를 레지스터에 갱신하는 처리 장치.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 산술·논리·비교·시프트 연산을 수행하는 실행 회로.
- **제어장치(Control Unit, CU)**: 명령어를 해석해 ALU·레지스터·버스에 제어 신호를 발생시키는 순서 제어 회로.
- **레지스터(Register)**: CPU 내부에서 피연산자·주소·명령어·상태를 임시 보관하는 고속 저장소.
- **버스(Bus)**: 주소·데이터·제어 신호를 구성요소 사이에 전달하는 공유 전송 경로.

</details>

- 정의/개념: **연산·제어·저장·전송** 기능을 분담하여 컴퓨터 프로그램을 처리하는 핵심 하드웨어 아키텍처
- 배경/필요성: 기능 통합 시 회로 복잡도 급증 및 제어 신호 병목으로 **명령어 처리 지연** 발생

#### 한줄 요약
- CPU는 계산하는 ALU, 순서를 정하는 CU, 값을 잡아두는 레지스터, 이들을 잇는 버스가 한 팀으로 명령어 한 줄을 처리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 경로(Datapath)**: 피연산자와 연산 결과가 레지스터·ALU·메모리 사이를 이동하는 회로 경로.
- **제어 신호(Control Signal)**: CU가 레지스터 기록·ALU 연산 선택·버스 방향을 지시하는 하드웨어 신호.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터.

</details>

- CU가 명령어를 해석하여 **제어 신호**를 발생시키고 각 구성요소의 동작 순서 제어
- ALU와 레지스터가 **데이터 경로**를 형성해 피연산자 입력·연산·결과 보관을 연속 수행
- 버스가 주소·데이터·제어 신호를 공유 전송해 구성요소 간 결합도를 낮춤

#### 한줄 요약
- CU가 순서를 정하면 ALU·레지스터가 데이터 경로에서 값을 처리하고, 버스가 신호를 전달해 네 구성요소가 하나의 실행 흐름을 만든다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 레지스터(Instruction Register, IR)**: 인출한 명령어를 CU가 해석할 때까지 보관하는 레지스터.
- **명령어 디코더(Instruction Decoder)**: IR의 연산 코드와 피연산자 필드를 제어 정보로 변환하는 CU 내부 회로.
- **상태 레지스터(Status Register)**: ALU 연산 결과의 조건 코드(영·음·올림수·오버플로)를 보관하는 레지스터.

</details>

```text
[CPU]
├─ CU
│  ├─ 명령어 디코더
│  └─ 제어 신호 발생기
├─ ALU
├─ 레지스터
│  ├─ PC
│  ├─ IR
│  └─ 상태 레지스터
└─ 버스 (주소·데이터·제어)
```

선의 의미: 가지(`├─`)는 소유 관계, CPU 경계 밖과 버스의 연결은 공유 전송 경로

| 구성요소 | 책임 |
|:---|:---|
| CU | **제어 신호** 발생으로 연산·전송 순서 결정 |
| ALU | 산술·논리·비교 연산 수행 |
| PC | 다음 명령어 주소 보관·자동 증가 |
| IR | 인출 명령어 보관으로 CU 해석 대기 |
| 상태 레지스터 | 연산 조건 코드 보관으로 분기 판단 근거 제공 |
| 버스 | 주소·데이터·**제어 신호** 공유 전달 |

#### 한줄 요약
- CPU 내부는 제어·연산·상태 보관·신호 전달의 네 책임으로 나뉘며, 각 구성요소가 서로의 영역을 침범하지 않아 교체·확장이 가능하다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch)**: PC가 지정한 주소에서 명령어를 버스를 통해 IR로 가져오는 파이프라인 첫 단계.
- **명령어 해독(Instruction Decode)**: CU가 IR의 연산 코드와 피연산자 정보를 해석해 제어 신호를 결정하는 단계.
- **기록 단계(Write Back)**: ALU 연산 결과를 목적 레지스터에 반영하는 최종 단계.

</details>

```text
     PC → 버스 → 메모리
                  │
            1. 명령어 인출: IR에 적재
                  │
            2. 명령어 해독: CU → 제어 신호
                  │
            ┌─────┴──────┐
     3a. ALU 실행     3b. 메모리 접근
            └─────┬──────┘
                  │
            4. 결과 기록: 레지스터 갱신·PC 증가
```

**동작 원리**

1. **명령어 인출**: PC 주소로 버스를 통해 명령어를 IR에 적재
2. **명령어 해독**: CU가 연산 코드 해석 후 제어 신호 발생
3. **ALU 실행 또는 메모리 접근**: 연산 수행 또는 메모리 데이터 전송
4. **결과 기록**: 연산 결과를 레지스터에 기록하고 PC 갱신

#### 한줄 요약
- 명령어 하나는 인출→해독→실행→기록의 네 단계를 거치며, 각 단계마다 CU가 버스·ALU·레지스터를 조정해 데이터가 올바른 경로를 따르게 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로아키텍처(Microarchitecture)**: 동일 ISA를 구현하기 위해 CPU 내부 구성요소를 배치·연결하는 방식.
- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 프로그램에 보이는 명령어·레지스터·예외 동작의 규약.

</details>

| CPU 구현 유형 | 단순 CPU (단일 사이클) | 고성능 파이프라인 CPU | 슈퍼스칼라/비순서 CPU |
|:---|:---|:---|:---|
| 적용 기준 | 초저전력 임베디드 제어기 | 범용 마이크로프로세서 | 고성능 서버 및 HPC 연산 |
| 핵심 특징 | 단일 데이터 경로·하드와이어드 CU | **다단계 파이프라이닝 및 포워딩** | **다중 명령어 동시 디코딩·비순서 실행** |
| 한계 | 클록 주기가 가장 긴 연산에 종속 | 데이터·구조 해저드로 인한 스톨 | 제어 회로 복잡도 및 전력 소모 급증 |

#### 한줄 요약
- CPU 구현은 단순성과 병렬성에서 달라지지만, 프로그램에 보이는 ISA 약속은 어느 구현이든 지켜야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 앞선 명령어의 결과가 레지스터에 기록되기 전에 후속 명령어가 그 값을 요구하는 의존성 충돌.
- **포워딩(Forwarding)**: 레지스터 기록 완료 전 ALU 결과를 후속 연산의 입력으로 직접 전달하는 기법.
- **파이프라인 플러시(Pipeline Flush)**: 잘못 진행한 명령어를 파이프라인에서 제거해 올바른 실행 경로로 복귀하는 동작.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **데이터 해저드**로 이전 결과 미준비 시 오래된 값 읽기 | **포워딩**과 스톨 제어 적용 | 잘못된 피연산자 사용 방지 |
| 분기 결과 지연으로 잘못된 명령어 실행 | 분기 판정 후 **파이프라인 플러시** | 잘못된 실행 경로 제거 |
| 버스 요청 동시 집중으로 전송 지연 | 버스 중재·전송 우선순위 설정 | 공유 경로 대기 시간 감소 |

#### 한줄 요약
- CPU는 빠른 연산만으로 충분하지 않으며, 값 의존성·잘못된 실행 경로·버스 경쟁까지 통제해야 올바른 결과를 낼 수 있다.

## Ⅶ. 결론

- 저전력 제어는 **단순 CPU**, 고성능 연산은 **파이프라인/슈퍼스칼라** 선택

#### 한줄 요약
- CPU 구성은 부품 이름 암기 문제가 아니라, 목표 성능에 맞게 제어·연산·저장·전달 책임을 어떻게 배분하느냐의 설계 문제이다.
