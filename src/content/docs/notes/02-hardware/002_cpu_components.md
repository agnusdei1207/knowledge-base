## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 인출·해독·실행하고 컴퓨터 전체 시스템의 데이터 흐름과 동작을 제어하는 핵심 하드웨어 장치.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 제어장치의 지시에 따라 산술 연산, 논리 연산, 비트 시프트 및 조건 비교를 수행하는 CPU 내부 핵심 실행 회로.
- **제어장치(Control Unit, CU)**: 메모리에서 인출한 명령어를 해독하여 ALU, 레지스터, 버스의 동작 타이밍과 데이터 전송을 지휘하는 마이크로 제어 신호 발생 장치.
- **레지스터(Register)**: CPU 내부 데이터패스에서 명령어·주소·피연산자·상태를 고속 보관하는 기억소자.
- **내부 버스(Internal Bus)**: CPU 내부 구성요소 간에 주소, 데이터, 제어 신호를 상호 교환하기 위한 공통 신호 전송 선로.

</details>

- 정의/개념: 프로그램 명령어를 인출·해독하여 연산을 수행하고 데이터 흐름을 통제하기 위해 **제어장치(CU)**와 **산술논리연산장치(ALU)**, 레지스터 파일 및 내부 버스로 구성된 프로세서 핵심 하드웨어 아키텍처
- 배경/필요성: 단일 통합 회로 구조에서는 연산·제어·기억 동작 간 자원 경합과 주기억장치 왕복 지연이 누적되므로 연산·제어·저장을 전담 유닛으로 분리하고 피연산자를 CPU 내부 **레지스터**에 두어 메모리 병목을 해소

#### 한줄 요약
- CPU는 연산(ALU), 지휘(CU), 고속 저장(레지스터), 연결 통로(버스)의 네 책임이 분리되어 1클록 단위로 맞물려 돌아가는 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터패스(Datapath)**: ALU, 레지스터 파일, 내부 버스 등 실제 연산 수행과 피연산자 데이터의 이동이 일어나는 하드웨어 실행 경로.
- **제어 신호(Control Signal)**: CU가 매 사이클마다 레지스터 쓰기 인에이블, ALU 연산자 선택, 멀티플렉서 분기 등을 지시하는 전압 신호.
- **프로그램 카운터(Program Counter, PC)**: 다음에 실행할 명령어의 메모리 주소를 보관하며, 순차 인출 시 자동 증가하고 분기 시 대상 주소로 갱신되는 특수 레지스터.

</details>

- 제어와 실행 분리: CU의 **제어 신호** 생성과 **데이터패스**의 실행이 분리되어 단일 하드웨어로 다양한 기계어 명령어를 유연하게 처리
- 고속 데이터 공급: **레지스터 파일**과 ALU의 직접 연결로 주기억장치 접근 없이 단일 사이클 피연산자 공급 지원
- 공통 버스 공유: **내부 버스**를 통해 구성요소 간 배선 복잡도를 절감하되 동시 전송 불가에 따른 버스 경합을 중재 회로로 통제

#### 한줄 요약
- 제어장치가 지휘 신호를 만들고 데이터패스가 연산을 수행하는 구조적 분리를 통해 범용성과 고속 처리 능력을 동시에 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 레지스터(Instruction Register, IR)**: 메모리에서 인출된 현재 실행 대상 명령어를 해독 완료 시까지 임시 보관하는 레지스터.
- **명령어 디코더(Instruction Decoder)**: IR의 Opcode 필드를 해석하여 해당 명령어에 대응하는 세부 마이크로 연산 제어 신호를 생성하는 논리 회로.
- **상태 플래그 레지스터(Status/Flags Register)**: ALU 연산 결과에 따라 Zero, Carry, Overflow, Sign 등의 상태 비트를 저장하여 조건부 분기 판정을 지원하는 레지스터.

</details>

```text
[CPU 프로세서 코어]
  │
  ├─ [제어장치 (CU)]
  │     ├─ [명령어 디코더] (Opcode 해석)
  │     └─ [마이크로시퀀서] (제어 신호 분배)
  │
  ├─ [연산장치 (ALU)]
  │     ├─ [산술·논리 연산기] (데이터 연산 실행)
  │     └─ [상태 플래그] (Zero/Carry/Sign)
  │
  ├─ [레지스터 파일]
  │     ├─ [제어 레지스터] (PC, IR)
  │     └─ [데이터 레지스터] (GPR, SP)
  │
  └─ [내부 버스 인터페이스] (데이터·주소·제어 공유)
```

선의 의미: CPU 코어 내부 4대 핵심 구성요소의 계층 및 소속 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 제어장치(CU) | **명령어 디코더**를 통한 명령어 해독과 단계별 **제어 신호** 분배 및 타이밍 통제 |
| 산술논리연산장치(ALU) | 가산·비트연산 수행 및 조건 분기를 위한 **상태 플래그** 생성 |
| 레지스터 파일 | **명령어 레지스터(IR)**·PC 및 범용 레지스터를 통한 초고속 피연산자 보관 |
| 내부 버스 | CPU 내부 유닛 간 주소, 데이터 및 제어 신호의 상호 **공유 전송** 담당 |

#### 한줄 요약
- CPU 내부는 제어장치(CU), 실행 연산기(ALU), 저장소(레지스터), 연결망(버스)이 명확한 계층적 포함 관계를 형성하며 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 실행 주기(Instruction Cycle)**: 인출(Fetch) ➔ 해독(Decode) ➔ 실행(Execute) ➔ 저장(Write-Back)으로 이어지는 명령어 한 개의 처리 과정.

</details>

```text
[프로그램 카운터(PC) 기반 메모리 주소 지정]
                    │
                    ▼
          1. 명령어 인출 (Fetch)
                    │ (IR 적재 및 PC 증가)
                    ▼
          2. 명령어 해독 (Decode)
                    │ (CU 명령어 디코딩 및 제어신호 생성)
                    ▼
          3. 피연산자 인출 (Operand Fetch)
                    │ (레지스터 파일/메모리 참조)
                    ▼
          4. 명령어 실행 (Execute)
                    │ (ALU 연산 및 상태 플래그 갱신)
                    ▼
          5. 결과 기록 (Write-Back)
                    │ (목적 레지스터 갱신 완료)
                    ▼
[차기 명령어 인출 사이클 개시]
```

분기 결과: 산술·논리 연산은 레지스터 간 고속 처리로 완결되고, 메모리 연산은 버스 접근 지연이 수반되며, 분기 연산은 **프로그램 카운터(PC)** 갱신을 통해 제어 흐름을 전환함

**동작 원리**

1. **명령어 인출**: PC가 가리키는 주소의 명령어를 메모리에서 인출하여 내부 버스를 거쳐 IR에 적재하고 PC를 차기 주소로 갱신함
2. **명령어 해독**: 제어장치 내부 디코더가 IR의 Opcode를 해석하여 ALU 연산 선택 및 레지스터 인에이블 제어 신호를 생성함
3. **피연산자 인출**: 해독된 레지스터 주소를 바탕으로 레지스터 파일에서 연산에 필요한 소스 피연산자 데이터를 인출함
4. **명령어 실행**: ALU가 공급된 피연산자를 바탕으로 제어 신호에 맞추어 산술·논리 연산을 실행하고 상태 플래그를 세팅함
5. **결과 기록**: ALU 연산 결과값 또는 메모리에서 로드된 데이터를 목적 범용 레지스터에 기록하여 단일 명령어 주기를 완결함

#### 한줄 요약
- 명령어 실행 주기는 인출·해독·피연산자인출·실행·기록 단계를 거치며 CU, ALU, 레지스터, 버스가 교대로 활성화된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 사이클 CPU(Single-Cycle CPU)**: 모든 명령어의 실행 주기를 단 1클록 안에 완료하도록 설계한 구조.
- **파이프라인 CPU(Pipelined CPU)**: 명령어 주기를 여러 단계로 분할하여 서로 다른 명령어를 각 단계에서 중첩 실행하는 구조.
- **슈퍼스칼라 CPU(Superscalar CPU)**: 파이프라인을 복수 개 병렬 배치하여 사이클당 2개 이상의 명령어를 동시 발행·실행하는 고성능 구조.

</details>

| CPU 구현 방식 | 단일 사이클 CPU | 파이프라인 CPU | 슈퍼스칼라 / 비순서(OoO) CPU |
|:---|:---|:---|:---|
| 적용 기준 | **회로 면적 극소화** 및 교육용 모델 | **명령어 처리량 향상** 및 범용 프로세서 | **명령어 수준 병렬성(ILP)** 극대화 요구 |
| 핵심 특징 | 단일 데이터패스에서 1명령어 1클록 완결 | 단계 분할을 통한 **명령어 중첩 실행** | 복수 실행 유닛 병렬 배치 및 **동적 재배치** |
| 한계 | 가장 긴 명령어 지연에 클록 주파수 제약 | 자원·데이터 충돌로 **파이프라인 스톨** 발생 | 제어 로직 복잡도 및 발열·전력 소모 급증 |

#### 한줄 요약
- 단순 제어에는 단일 사이클이 적합하고, 표준 프로세서는 파이프라인을 쓰며, 극대화된 성능 요구에는 슈퍼스칼라와 비순서 실행이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 후속 명령어가 선행 명령어의 레지스터 기록 완료 전 해당 값을 참조할 때 발생하는 데이터 의존성 충돌.
- **포워딩(Forwarding/Bypassing)**: 레지스터 쓰기(WB)를 기다리지 않고 ALU 출력 또는 메모리 버퍼 값을 후속 명령어의 실행(EX) 입력으로 직결하는 하드웨어 경로.
- **분기 예측(Branch Prediction)**: 조건부 분기 명령어의 분기 여부와 목적 주소를 사전에 예측하여 파이프라인 중단 없이 인출을 지속하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 선행 연산 결과 미기록 상태에서 후속 명령어가 레지스터 참조 시 데이터 해저드 충돌 | **포워딩 회로** 및 인터록 스톨 기법 적용 | 파이프라인 버블 최소화 및 레지스터 데이터 무결성 보장 |
| 조건부 분기 판정 지연으로 인한 파이프라인 인출 중단 및 처리량 저하 | 2비트 포화 카운터 기반 **동적 분기 예측기** 도입 | 제어 해저드 손실 최소화 및 파이프라인 연속 공급 달성 |
| 복수 기능 유닛의 동시 메모리 접근 요구에 따른 내부 버스 경합 | L1 I/D **캐시 분리** 및 우선순위 버스 중재기 구축 | 명령어 인출과 데이터 로드의 충돌 방지 및 대역폭 확보 |

#### 한줄 요약
- CPU 성능 최적화는 하드웨어 유닛 간의 대기 시간을 줄이는 데 있으며, 포워딩, 분기 예측, 캐시 계층 분리가 필수적인 공학적 대책이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **도메인 특화 가속기(Domain-Specific Accelerator, DSA)**: 범용 CPU 대비 특정 연산 패턴(행렬곱, 추론 등)을 전용 하드웨어로 처리하여 성능·전력 효율을 극대화하는 가속 프로세서.
- **NPU(Neural Processing Unit)**: 딥러닝 추론·학습의 행렬·텐서 연산에 특화된 도메인 전용 프로세서.

</details>

- CPU는 CU·ALU·레지스터·버스의 유기적 분업 체계로서 컴퓨팅의 핵심 연산 엔진으로 정착하였으며, 단일 코어 클록 주파수 한계를 넘기 위해 멀티코어 병렬화 및 **NPU·DSA**와 결합하는 이기종 SoC로 확장되고 있어, 명령어 수준 병렬성(ILP) 향상에 따른 회로 복잡도·전력 밀도(TDP) 상충을 정량 분석한 파이프라인 깊이 설계

#### 한줄 요약
- CPU는 연산·제어·저장·전송 유닛의 상호 협력 체계이며 해저드 통제와 이기종 가속기 결합을 통해 성능과 전력 효율을 완성한다.
