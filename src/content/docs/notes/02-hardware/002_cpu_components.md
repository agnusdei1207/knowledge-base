## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 해석하고 연산 결과와 실행 상태를 갱신하는 처리 장치입니다.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 산술, 논리, 비교, 시프트 연산을 수행하는 실행 회로입니다.
- **제어장치(Control Unit, CU)**: 명령어와 상태를 해석해 구성요소의 동작 순서를 제어하는 회로입니다.
- **레지스터(Register)**: CPU 내부에서 피연산자, 주소, 상태를 빠르게 보관하는 저장소입니다.
- **버스(Bus)**: 주소, 데이터, 제어 신호를 구성요소 사이에 전달하는 공유 연결 경로입니다.

</details>

- 정의/개념: ALU·CU·레지스터·버스가 협력하는 **명령어 실행 구조**
- 배경/필요성: 연산·제어·상태·전송 책임의 **기능 분리**

#### 한줄 요약

- CPU는 계산하는 ALU, 순서를 정하는 CU, 값을 저장하는 레지스터, 이를 잇는 버스가 함께 명령어를 처리합니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 경로(Datapath)**: 피연산자와 연산 결과가 레지스터, ALU, 메모리 사이를 이동하는 회로 경로입니다.
- **제어 신호(Control Signal)**: 레지스터 기록, ALU 연산, 버스 선택을 지시하는 하드웨어 신호입니다.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터입니다.

</details>

- CU: 명령 해석과 **제어 신호 생성**
- ALU·레지스터: 계산과 결과 보관을 잇는 **데이터 경로**
- 버스: 주소·데이터·제어 정보의 **공유 전송 매체**

#### 한줄 요약

- CU가 길을 정하면 ALU와 레지스터가 값을 처리하고, 버스가 필요한 신호와 데이터를 전달합니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 디코더(Instruction Decoder)**: 명령어의 연산 코드와 피연산자 필드를 제어 정보로 해석하는 회로입니다.
- **상태 레지스터(Status Register)**: 연산 결과의 조건 코드와 실행 상태를 보관하는 레지스터입니다.

</details>

```text
[CPU]
├─ CU
│  └─ 명령어 디코더
├─ ALU
├─ 레지스터
│  ├─ PC
│  └─ 상태 레지스터
└─ 버스
```

| 구성요소 | 책임 |
|:---|:---|
| CU | 명령 해석과 제어 신호 생성 |
| ALU | 산술·논리·비교 연산 수행 |
| 레지스터 | 피연산자, 주소, 상태의 임시 보관 |
| 버스 | 주소·데이터·제어 신호의 전달 |

#### 한줄 요약

- CPU 내부는 제어, 연산, 상태, 전달의 네 책임으로 나누어지며 각 구성요소가 서로의 일을 대신하지 않습니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch)**: PC가 지정한 위치에서 다음 명령어를 가져오는 단계입니다.
- **명령어 해독(Instruction Decode)**: 명령어의 연산과 피연산자 지정 정보를 해석하는 단계입니다.
- **기록 단계(Write Back)**: 연산 결과를 목적 레지스터나 메모리에 반영하는 단계입니다.

</details>

```text
[1. 명령어 인출]
          │
          ▼
[2. 명령어 해독]
          │
          ▼
[3. ALU 실행 또는 메모리 접근]
          │
          ▼
[4. 결과 기록과 PC 갱신]
```

동작 원리:

1. 명령어 인출: PC가 가리키는 명령어를 버스로 확보
2. 명령어 해독: CU가 연산과 데이터 경로를 선택
3. ALU 실행 또는 메모리 접근: ALU가 연산하거나 버스가 데이터 전달
4. 결과 기록과 PC 갱신: 레지스터에 결과를 쓰고 다음 실행 위치 확정

#### 한줄 요약

- 명령어 하나는 가져오기, 해석, 실행, 기록 순서를 거치며 CU는 매 단계의 구성요소를 조정합니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로아키텍처(Microarchitecture)**: 같은 ISA를 실행하기 위해 CPU 내부 구성요소를 배치하고 제어하는 구현 방식입니다.
- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 프로그램에 보이는 명령어, 레지스터, 예외 동작의 규약입니다.

</details>

- 단순 CPU: 짧은 데이터 경로와 **직접 제어 방식**
- 고성능 CPU: 다수 실행 경로와 **병렬 제어 방식**
- 공통 제약: 동일 ISA의 관찰 가능한 결과와 예외 상태 유지

#### 한줄 요약

- CPU 구현은 단순성과 병렬성에서 달라져도, 프로그램에 보이는 ISA의 약속은 지켜야 합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 앞선 명령어의 결과가 준비되기 전에 다음 명령어가 그 값을 요구하는 의존성입니다.
- **포워딩(Forwarding)**: 아직 레지스터에 기록되지 않은 실행 결과를 후속 연산에 직접 전달하는 기법입니다.
- **파이프라인 플러시(Pipeline Flush)**: 잘못 진행한 명령어를 파이프라인에서 제거하는 복구 동작입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 해저드로 이전 결과를 읽기 | 포워딩과 대기 제어 적용 | 오래된 값 사용 방지 |
| 분기 결과가 늦어 잘못된 명령 실행 | 분기 판정 뒤 파이프라인 플러시 | 잘못된 경로 결과 제거 |
| 버스 요청이 동시에 몰려 전송 지연 | 버스 중재와 전송 우선순위 설정 | 공유 경로 대기 시간 감소 |

#### 한줄 요약

- CPU는 빠른 연산만으로 충분하지 않고, 값 의존성과 잘못된 실행, 공유 버스의 경쟁까지 통제해야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **처리량(Throughput)**: 일정 시간 동안 CPU가 완료하는 명령어 또는 작업의 양입니다.

</details>

- 목표 **처리량**과 전력·면적 제약을 기준으로, 단순 제어가 우선이면 짧은 데이터 경로를, 병렬 실행이 우선이면 확장된 CU·ALU·버스 구성을 선택

#### 한줄 요약

- CPU 구성은 부품 이름을 외우는 문제가 아니라, 목표 성능에 맞게 제어와 연산, 저장, 전송을 맞추는 설계 문제입니다.
