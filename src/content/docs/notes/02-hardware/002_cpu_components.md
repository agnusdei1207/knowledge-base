## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 기계어 명령어를 인출, 해독, 실행, 기록하여 연산을 제어하는 핵심 프로세서이다.
- **제어장치(Control Unit, CU)**: 오퍼코드를 해독하여 내부 데이터 경로 및 버스의 제어 신호를 생성하는 장치이다.
- **산술논리장치(Arithmetic Logic Unit, ALU)**: 제어 신호에 따라 산술 및 논리 연산을 수행하는 조합 논리 회로이다.
- **내부 버스(Internal Processor Bus)**: CPU 코어 내부에서 통신을 담당하는 선로이다.

</details>

- 정의: 연산, 제어, 저장, 전송 장치가 결합하여 명령어를 처리하는 컴퓨터의 핵심 모듈인 **중앙 처리 장치** 체계
- 배경: 제어 흐름 관리와 동기화가 불가능한 단순 연산 회로의 한계를 극복하기 위해 제어와 데이터를 분리할 필요가 있음

#### 한줄 요약

- 제어 장치의 명령어 인출•해독과 데이터 경로의 연산•기록 기능을 통합하여 프로세서 명령어 주기를 완결한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제어 경로(Control Path)**: 명령어 해독 결과에 따라 ALU, 레지스터 등의 활성화를 통제하는 로직 회로이다.
- **데이터 경로(Data Path)**: 피연산자 레지스터, ALU, 버스로 구성되어 실제 데이터를 옮기고 연산하는 선로이다.
- **레지스터(Register)**: 플립플롭과 래치 회로로 구성되어 피연산자와 메모리 주소를 초고속으로 보관하는 저장 소자이다.
- **클록 엣지(Clock Edge)**: 디지털 회로에서 신호를 저장하거나 상태를 전환하는 클록 파형의 상승 또는 하강 시점이다.

</details>

- **제어 경로**의 해독 신호를 바탕으로 **데이터 경로** 상의 멀티플렉서 선택 및 연산 모드를 실시간으로 결정함.
- **레지스터**를 중심으로 피연산자 공급 체계를 구축하여 메모리 접근 빈도를 줄이고 지연 시간을 극소화함.
- 기준 **클록 엣지**에 맞춰 연산 결과와 상태를 정밀하게 갱신하여 명령어 실행의 안정성을 보장함.

#### 한줄 요약

- 제어장치의 신호를 바탕으로 데이터 경로 연산을 제어하며, 클록 동기화를 통해 레지스터 상태를 정확히 갱신한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **산술논리장치(ALU)**: 범용 레지스터가 제공한 피연산자를 바탕으로 정수 및 논리 연산을 실행하는 장치이다.
- **제어장치(CU)**: 명령어 레지스터에 적재된 오퍼코드를 해독하는 컨트롤 장치이다.
- **레지스터 파일(Register File)**: 범용 레지스터 배열로 묶어 동시 접근 포트를 제공하는 고속 데이터 배열이다.
- **특수 목적 레지스터(SPR)**: PC, IR 등 프로세서의 위치 및 상태 유지를 위한 전용 레지스터이다.
- **내부 버스(Internal Bus)**: 레지스터와 ALU 입력/출력 간 데이터 전송을 보장하는 프로세서 내 경로이다.
- **제어 신호(Control Signal)**: 레지스터 입출력, 연산자 선택 등을 통제하는 1비트/다비트 선로이다.

</details>

```text
+-------------------------------------------------------------------+
|                        CPU Core Architecture                      |
|                                                                   |
|   [ Control Path ]                     [ Data Path ]              |
|   +-------------------+                +----------------------+   |
|   | Control Unit (CU) |==Control Lines==> Register File(GPR)  |   |
|   +-------------------+                +----------------------+   |
|     | Instruction Deco.                  | Operand 1 & 2          |
|     v                                    v                        |
|   +-------------------+                +----------------------+   |
|   | SPR (PC, IR, PSR) |                |   ALU (Arithmetic)   |   |
|   +-------------------+                +----------------------+   |
|                                                  | Result         |
|                                                  v                |
|   <=============== Internal Processor Bus ===================>    |
+-------------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| 제어장치 | 명령 해독 및 타이밍별 **제어 신호** 생성 |
| 레지스터 파일 | 연산을 위한 **피연산자** 및 결과 초고속 보관 |
| 특수 목적 레지스터 | 실행 위치 추적 및 상태 관리 |
| 산술논리장치 | 제어 신호에 따른 산술 및 논리 연산 실행 |
| 내부 버스 | 코어 블록 간 **내부 버스**를 통한 신호 전송 |

#### 한줄 요약

- 제어 경로(CU, PC, IR)가 동작 타이밍을 통제하고, 데이터 경로(ALU, GPR)가 연산 및 결과 저장 라운드트립을 완수한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PC(Program Counter)**: 다음에 인출할 기계어 명령어의 주소값을 보유하는 특수 레지스터이다.
- **IR(Instruction Register)**: 메모리에서 인출한 명령어를 해독 직전까지 격리 보관하는 레지스터이다.
- **상태 비트(Status Bit)**: ALU 연산 결과(Zero, Carry 등) 여부를 기록하는 조건 플래그이다.
- **명령어 인출(Instruction Fetch)**: PC가 나타내는 메모리 주소에서 기계어를 읽어 IR에 적재하는 단계이다.
- **명령어 해독(Instruction Decode)**: CU가 명령어 필드를 분석하여 제어 신호를 생성하는 단계이다.
- **피연산자 읽기(Operand Fetch)**: 지정된 레지스터 번호나 메모리 주소에서 실제 데이터 피연산자를 읽는 단계이다.
- **연산 실행(Execute)**: ALU가 제어 신호에 맞추어 피연산자에 대한 산술 논리 계산을 진행하는 단계이다.
- **결과 기록(Write-Back)**: 연산 최종 결과값을 목표 레지스터에 기록하고 상태 비트를 저장하는 단계이다.

</details>

```text
[PC 주소 요청] ──> 1. 명령어 인출
                         │
                         ▼
                   2. 명령어 해독
                         │
                         ▼
                   3. 피연산자 읽기
                         │
                         ▼
                   4. 연산 실행
                         │
                         ▼
                   5. 결과 기록 ──> [레지스터 갱신]
```

### 동작 원리

1. 명령어 인출: **PC**가 가리키는 메모리 주소의 명령어를 가져와 **IR**에 저장하고 PC 주소를 증가시킴.
2. 명령어 해독: 제어장치가 **IR**의 오퍼코드를 해독하여 ALU 연산 종류와 레지스터 읽기 신호를 구동함.
3. 피연산자 읽기: 명령어가 지시하는 레지스터 파일에 접근하여 입력 데이터 2개를 버스에 연결함.
4. 연산 실행: ALU가 지정된 연산을 실행하고 결과를 출력하는 동시에 상태 레지스터에 **상태 비트**를 갱신함.
5. 결과 기록: 연산 결과를 지정된 레지스터에 기록하고 명령어 1주기를 완료함.

#### 한줄 요약

- 인출, 해독, 피연산자 읽기, 연산 실행, 결과 기록의 5단계 사이클이 순차적으로 맞물려 실행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **범용 레지스터(General-Purpose Register, GPR)**: 다양한 피연산자와 중간 결과를 임시 저장하는 다용도 레지스터이다.
- **스택 포인터(Stack Pointer, SP)**: 함수 호출 파라미터를 위한 메모리 스택의 최상단 주소를 추적하는 레지스터이다.
- **상태 레지스터(Program Status Register, PSR)**: 프로세서의 동작 모드와 ALU 결과 플래그를 관리하는 레지스터이다.
- **제어 레지스터(Control Register)**: 프로세서 가상화 보호 모드 등을 보관하는 제어 소자이다.
- **주소 레지스터(Address Register)**: 데이터 전송 시 참조 주소를 지정하기 위해 특화된 레지스터이다.

</details>

| 유형 | 종류 | 데이터 | 역할 |
|:---|:---|:---|:---|
| 범용 레지스터 | **GPR** | 연산 피연산자 및 중간 결과 | 메모리 접근 횟수 절감 및 데이터 직접 공급 |
| 제어 레지스터 | **PC**, **IR** | 다음 명령 주소 및 현재 기계어 | 명령어 제어 흐름의 연쇄성 유지 |
| 주소 레지스터 | **SP**, MAR | 메모리 스택 탑 주소 | 함수 복귀 주소 관리 및 메모리 위치 추적 |
| 상태 레지스터 | **PSR** | 오버플로우 플래그 및 마스크 | 조건 분기 판단 기준 제공 및 예외 제어 |

#### 한줄 요약

- 범용 레지스터는 연산 데이터를 공급하며, 제어/상태 레지스터는 실행 문맥 유지와 제어 흐름을 관장한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **다중 포트 레지스터 파일(Multi-Ported Register File)**: 단일 클록에 복수의 읽기와 쓰기를 병렬로 동시 수행하는 회로 구조이다.
- **데이터 해저드(Data Hazard)**: 결과 기록 전에 다음 명령어가 데이터에 접근하여 선후 관계가 파괴되는 의존성 문제이다.
- **포워딩(Forwarding)**: ALU 연산 결과를 레지스터 기록 전 즉각 바이패스 시켜 연산 입력으로 재사용하는 기술이다.
- **파이프라인 인터록(Pipeline Interlock)**: 의존성이 해결될 때까지 파이프라인 신호를 동결해 Stall을 발생시키는 장치이다.
- **버스 경합(Bus Contention)**: 다수의 하드웨어가 칩 내부 버스 자원을 동시에 점유하려 하여 충돌이 일어나는 현상이다.
- **버스 중재(Bus Arbitration)**: 요청자 간 우선순위를 할당하여 버스 점유 권한을 교통정리하는 메커니즘이다.
- **설정•유지 시간(Setup/Hold Time)**: 레지스터 데이터 입력 시 클록 신호 전후로 안정되게 유지되어야 하는 최소 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동시 접근 시 레지스터 병목 | 2-Read 이상의 **다중 포트 레지스터 파일** | 동일 주기에 피연산자 인출 병렬성 확보 |
| 기록 지연으로 발생한 **데이터 해저드** | 즉시 바이패스 시키는 **포워딩** 및 **파이프라인 인터록** | 레지스터 대기 시간을 우회하여 처리량 유지 |
| 단일 통로 점유에 의한 **버스 경합** | 우선순위를 매기는 **버스 중재** 회로 내장 | 내부 데이터 이동 충돌 예방 |
| 고속화로 인한 **설정•유지 시간** 위반 | Critical Path를 분석하여 여유 마진 확보 | 고속 동작 메타스태빌리티 방지 |

#### 한줄 요약

- 다중 포트 레지스터, 데이터 포워딩, 파이프라인 정지 통제 및 버스 중재를 통해 구조적 해저드와 데이터 해저드를 극복한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **명령어 집합 아키텍처(ISA)**: 프로세서 형태와 레지스터 구조를 정의하는 하드웨어와 소프트웨어 간 인터페이스 사양이다.
- **설정 시간 마진(Setup Time Margin)**: 클록 고속화 시 회로에 신호가 도달하여 완전히 안정되는 데 필요한 여유 시간 간격이다.

</details>

- **ISA**에 맞춘 적정 ALU 개수와 버스를 설계하고 **설정 시간 마진** 검증 필수

#### 한줄 요약

- 대상 ISA 목표에 맞추어 프로세서 데이터 경로를 최적화하고 안정적인 타이밍 설계를 완성해야 한다.
