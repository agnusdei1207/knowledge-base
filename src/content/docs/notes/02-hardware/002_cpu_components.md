## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 기계어 명령어를 인출, 해독, 실행, 기록하여 연산을 제어하는 핵심 프로세서.
- **제어장치(Control Unit, CU)**: 오퍼코드를 해독하여 내부 데이터 경로 및 버스의 제어 신호를 생성하는 장치.
- **산술논리장치(Arithmetic Logic Unit, ALU)**: 제어 신호에 따라 산술 및 논리 연산을 수행하는 조합 논리 회로.
- **내부 버스(Internal Processor Bus)**: CPU 코어 내부의 레지스터, ALU, 제어장치 간 데이터 전송 선로.

</details>

- 정의/개념: 연산(ALU), 제어(CU), 저장(Register), 전달(Bus)의 4대 핵심 구성요소가 결합하여 기계어 명령어를 인출·해독·실행·기록하는 중앙 처리 장치 체계
- 배경/필요성: 단순 연산 회로의 한계를 극복하고 **프로그램 내장 제어 흐름 및 초고속 데이터 경로의 클록 동기화 구현**

#### 한줄 요약

- 제어장치의 명령 해독과 데이터 경로의 연산·기록으로 **명령어 주기 완결**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제어 경로(Control Path)**: 명령어 해독 결과에 따라 ALU와 레지스터의 입출력을 통제하는 로직 회로.
- **데이터 경로(Data Path)**: 피연산자 레지스터, ALU, 버스로 구성되어 실제 데이터를 이동하고 연산하는 선로.
- **클록 엣지(Clock Edge)**: 디지털 회로에서 신호를 저장하거나 상태를 전환하는 클록 파형의 상승 또는 하강 시점.

</details>

- **제어 경로**의 해독 신호 기반 데이터 경로 연산 모드 실시간 결정
- **레지스터 파일** 중심 피연산자 공급을 통한 메모리 접근 지연 최소화
- 기준 **클록 엣지** 동기화 기반 연산 결과 및 상태 플래그 정밀 갱신

#### 한줄 요약

- **제어 신호와 클록 동기화**로 데이터 경로 연산 및 레지스터 상태 갱신

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터 파일(Register File)**: 범용 레지스터들을 배열로 묶어 복수의 동시 접근 포트를 제공하는 고속 저장소.
- **특수 목적 레지스터(SPR)**: PC(프로그램 카운터), IR(명령어 레지스터) 등 프로세서 상태 유지를 위한 전용 레지스터.

</details>

```text
+-------------------------------------------------------------------+
|                        CPU Core Architecture                      |
|                                                                   |
|   [ Control Path ]                     [ Data Path ]              |
|   +-------------------+                +----------------------+   |
|   | Control Unit (CU) |==Control Lines==> Register File(GPR)  |   |
|   +-------------------+                +----------------------+   |
|     | Instruction Deco.                  | Operand 1 & 2          |
|     v                                    v                        |
|   +-------------------+                +----------------------+   |
|   | SPR (PC, IR, PSR) |                |   ALU (Arithmetic)   |   |
|   +-------------------+                +----------------------+   |
|                                                  | Result         |
|                                                  v                |
|   <=============== Internal Processor Bus ===================>    |
+-------------------------------------------------------------------+
```

선의 의미: 제어장치의 제어 신호와 레지스터 파일, ALU, 내부 버스 간의 데이터 경로 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 제어장치 | 명령 해독 및 타이밍별 **제어 신호** 생성 |
| 레지스터 파일 | 연산을 위한 **피연산자** 및 결과 초고속 보관 |
| 특수 목적 레지스터 | 실행 위치 추적 및 상태 관리 |
| 산술논리장치 | 제어 신호에 따른 산술 및 논리 연산 실행 |
| 내부 버스 | 코어 블록 간 **내부 버스**를 통한 신호 전송 |

#### 한줄 요약

- **제어 경로(CU, PC, IR)**와 **데이터 경로(ALU, GPR)**의 유기적 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 주기(Instruction Cycle)**: Fetch → Decode → Operand Fetch → Execute → Write-Back으로 이어지는 5단계 실행 사이클.

</details>

```text
[PC 주소 요청] ──> 1. 명령어 인출 (Fetch)
                         │
                         ▼
                   2. 명령어 해독 (Decode)
                         │
                         ▼
                   3. 피연산자 읽기 (Operand Fetch)
                         │
                         ▼
                   4. 연산 실행 (Execute)
                         │
                         ▼
                   5. 결과 기록 (Write-Back) ──> [레지스터 갱신]
```

**동작 원리**

1. **명령어 인출**: PC가 가리키는 메모리 주소에서 기계어를 가져와 IR에 적재하고 PC 증가
2. **명령어 해독**: 제어장치(CU)가 IR의 오퍼코드를 분석하여 ALU 연산 제어 신호 생성
3. **피연산자 읽기**: 지정된 레지스터 파일에서 연산에 필요한 입력 데이터 2개 인출
4. **연산 실행**: ALU가 산술/논리 계산을 수행하고 상태 레지스터(PSR) 플래그 갱신
5. **결과 기록**: 연산 결과값을 목표 레지스터에 저장하며 명령어 1주기 완료

#### 한줄 요약

- **인출-해독-읽기-실행-기록**의 5단계 명령어 사이클 순차 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PC / IR / SP / PSR**: 프로그램 카운터(PC), 명령어 레지스터(IR), 스택 포인터(SP), 프로그램 상태 레지스터(PSR).

</details>

| 레지스터 분류 | 범용 레지스터 (GPR) | 제어 레지스터 (PC, IR) | 상태/주소 레지스터 (PSR, SP) |
|:---|:---|:---|:---|
| 적용 기준 | 연산 피연산자 및 중간 결과 임시 저장 | 다음 명령어 주소 추적 및 현재 기계어 보관 | 산술 결과 플래그 판정 및 스택 프레임 관리 |
| 핵심 특징 | 다중 포트 구조, 초고속 읽기/쓰기 지원 | 프로그램 카운터(PC) 자동 증가, IR 해독 | Zero/Carry/Overflow 플래그, 스택 탑(Top) 유지 |
| 한계 및 위험 | 실리콘 면적 및 다중 포트 라우팅 복잡도 | 분기 예측 실패 시 파이프라인 플러시 발생 | 비동기 인터럽트 발생 시 문맥 교환 오버헤드 |

#### 한줄 요약

- 범용은 **연산 데이터 공급**, 제어/상태는 **실행 문맥 및 흐름 제어** 담당

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 포워딩(Data Forwarding)**: 연산 결과를 레지스터에 기록하기 전 ALU 출력단에서 다음 연산 입력단으로 직접 바이패스하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동시 접근 시 레지스터 병목 | 2-Read 이상의 **다중 포트 레지스터 파일** | 동일 주기에 피연산자 인출 병렬성 확보 |
| 기록 지연으로 발생한 **데이터 해저드** | 즉시 바이패스 시키는 **포워딩** 및 **파이프라인 인터록** | 레지스터 대기 시간을 우회하여 처리량 유지 |
| 단일 통로 점유에 의한 **버스 경합** | 우선순위를 매기는 **버스 중재** 회로 내장 | 내부 데이터 이동 충돌 예방 |
| 고속화로 인한 **설정•유지 시간** 위반 | Critical Path를 분석하여 여유 마진 확보 | 고속 동작 메타스태빌리티 방지 |

#### 한줄 요약

- **다중 포트·포워딩·버스 중재**로 구조적 및 데이터 해저드 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **타이밍 클로저(Timing Closure)**: 셋업 시간과 홀드 시간 마진을 확보하여 목표 클록 주파수에서 칩 오작동이 없음을 검증하는 설계 완료 상태.

</details>

- 목표 ISA 사양에 맞춘 **데이터 경로 최적화 및 셋업/홀드 시간 타이밍 마진 검증**

#### 한줄 요약

- **ISA 최적화와 타이밍 마진 검증**으로 프로세서 안정성 확보
