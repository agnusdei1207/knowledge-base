## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **중앙처리장치(Central Processing Unit, CPU)**: 프로그램 명령어를 인출·해석·실행하고 연산 결과 및 시스템 상태를 제어하는 컴퓨터의 핵심 처리 장치.
- **산술논리연산장치(Arithmetic Logic Unit, ALU)**: 산술·논리·비교·시프트 연산을 수행하고 결과에 따른 플래그(조건 코드)를 생성하는 핵심 실행 회로.
- **제어장치(Control Unit, CU)**: 명령어를 해독하여 ALU, 레지스터, 버스의 동작 타이밍 및 데이터 흐름을 통제하는 마이크로 제어 신호 발생 장치.
- **레지스터(Register)**: CPU 내부에서 명령어, 데이터 주소, 피연산자 및 상태 정보를 단일 클록 사이클 내에 고속으로 접근할 수 있도록 저장하는 초고속 임시 기억장치.
- **버스(Bus)**: CPU 내부 구성요소 간 또는 CPU와 외부 장치 간에 주소, 데이터, 제어 신호를 상호 공유하여 전송하는 공통 통신 선로.

</details>

- 정의/개념: 연산·제어·저장·전송의 네 책임을 분리한 구성요소가 협력해 명령어 한 개를 처리하는 **CPU** 내부 구조
- 배경/필요성: 단일 일체형 회로로는 **명령어 실행 단계별 검증 및 부품별 독립 개선 불가**

#### 한줄 요약
- 네 구성요소는 기능을 나눈 결과가 아니라 서로의 대기 시간을 흡수하기 위해 나뉜 것이며, 그래서 하나가 느리면 나머지가 모두 멈춘다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 경로(Datapath)**: 레지스터, ALU, 내부 버스 등 실제 연산 및 데이터 이동이 일어나는 하드웨어 경로로, 비트 폭과 파이프라인 단수가 처리 성능을 결정.
- **제어 신호(Control Signal)**: CU가 매 클록마다 레지스터 쓰기, ALU 연산 유형, 버스 전송 방향 등을 지시하여 데이터 경로의 동작을 동적으로 전환하는 제어선 신호.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출하여 실행할 명령어의 메모리 주소를 보관하며, 순차 실행 시 자동 증가하고 분기 시 목표 주소로 갱신되는 특수 레지스터.

</details>

- CU가 명령어를 해석해 **제어 신호**를 발생시키므로, 같은 **데이터 경로**가 명령어마다 다른 회로처럼 동작
- ALU와 레지스터가 데이터 경로를 이루어 피연산자 입력·연산·결과 보관을 한 클록 안에 연속 수행
- **버스** 기반 구성요소 간 결합도를 낮추는 대신 한 시점에 한 전송만 허용해 경합 지점이 됨

#### 한줄 요약
- 제어와 데이터를 분리한 덕분에 회로 하나로 모든 명령어를 처리할 수 있지만, 그 대가로 명령어마다 제어 신호를 새로 만들어야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 레지스터(Instruction Register, IR)**: 메모리에서 인출한 명령어 비트열을 CU가 해독을 완료할 때까지 임시 보관하는 레지스터.
- **명령어 디코더(Instruction Decoder)**: IR에 적재된 명령어의 Opcode와 피연산자 필드를 분석하여 해당 연산에 필요한 제어 신호 조합을 생성하는 회로.
- **상태 레지스터(Status Register)**: ALU 연산 결과로 발생하는 조건 플래그(Zero, Sign, Carry, Overflow 등)를 저장하여 조건부 분기의 판정 기준으로 제공하는 레지스터.

</details>

```text
[CPU]
├─ CU
│  ├─ 명령어 디코더
│  └─ 제어 신호 발생기
├─ ALU
├─ 레지스터
│  ├─ PC
│  ├─ IR
│  └─ 상태 레지스터
└─ 버스 (주소·데이터·제어)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 버스만이 CPU 경계 밖 메모리·입출력과 이어지는 공유 전송 경로

| 구성요소 | 책임 |
|:---|:---|
| CU | **제어 신호** 발생으로 연산·전송 순서 결정 |
| ALU | 산술·논리·비교 연산 수행 및 조건 코드 출력 |
| PC | 다음 명령어 주소 보관·순차 증가·분기 시 교체 |
| IR | 인출 명령어 보관으로 해독 중 메모리 재접근 차단 |
| 상태 레지스터 | 조건 코드 보관으로 분기 판단 근거 제공 |
| 버스 | 주소·데이터·제어 신호 공유 전달 |

#### 한줄 요약
- 레지스터는 값을 빨리 읽으려고 두는 것이 아니라 단계 사이에서 값이 사라지지 않게 붙잡는 장치이며, 그래서 단계가 늘면 레지스터부터 늘어난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch)**: PC가 가리키는 주소의 명령어를 메모리 버스를 통해 읽어와 IR에 적재하는 명령어 실행 주기의 첫 단계.
- **명령어 해독(Instruction Decode)**: CU의 디코더가 IR에 저장된 명령어 코드를 해석하여 필요한 피연산자 주소를 계산하고 실행 제어 신호를 확정하는 단계.
- **기록 단계(Write Back)**: ALU 연산 결과 또는 메모리 로드 데이터를 목적 레지스터(Destination Register)에 최종 반영하는 단계.

</details>

```text
PC 주소 → 버스 → 메모리
        │
   IR 적재 (명령어 인출)
        │
   명령어 해독: CU → 제어 신호 확정
        │
   연산 유형은 무엇인가?
 ┌──────┼─────────┐
산술·논리  메모리 접근    분기
 │        │          │
ALU 연산  주소 계산 후   조건 코드 판정
 │       버스 재사용     │
 │        │        ┌───┴───┐
 │        │      성립     미성립
 │        │        │        │
 └────┬───┘   PC ← 목표 주소  PC ← PC+4
      │
  기록 단계: 레지스터 갱신 후 PC 증가
```

분기 결과: 산술·논리는 ALU만 쓰고, 메모리 접근은 버스를 한 번 더 점유하며, 분기는 결과를 기록하는 대신 PC 자체를 교체

#### 한줄 요약
- 세 갈래가 쓰는 자원이 다르기 때문에 실행 단계의 소요 클록도 달라지며, 단일 사이클 설계가 가장 느린 갈래에 묶이는 이유가 여기에 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로아키텍처(Microarchitecture)**: 동일한 ISA를 기반으로 파이프라인 단수, 실행 유닛 수, 캐시 구조 등을 구체화한 하드웨어 설계 구현 방식.
- **명령어 집합 구조(Instruction Set Architecture, ISA)**: 하드웨어와 소프트웨어 간의 상호작용을 규정한 명령어 체계, 레지스터 집합, 메모리 주소 지정 방식 등의 추상화 인터페이스.

</details>

| CPU 구현 유형 | 단일 사이클 CPU | 파이프라인 CPU | 슈퍼스칼라·비순서 CPU |
|:---|:---|:---|:---|
| 적용 기준 | 초저전력 임베디드 제어기 | 범용 마이크로프로세서 | 고성능 서버·HPC 연산 |
| 핵심 특징 | 단일 데이터 경로에 하드와이어드 CU | 단계 분할로 명령어 중첩 실행 | 명령어를 동시에 해독하고 순서를 바꿔 실행 |
| 한계 | 클록 주기가 가장 긴 연산에 종속 | 의존성·자원 경합으로 스톨 발생 | 제어 회로 복잡도와 전력 소모 급증 |

#### 한줄 요약
- 세 구현은 같은 **ISA**를 지키므로 프로그램에는 동일하게 보이며, 차이는 전부 **마이크로아키텍처**에 감춘 병렬성의 양에서 나온다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 해저드(Data Hazard)**: 파이프라인 중첩 실행 시 선행 명령어의 결과가 레지스터에 기록되기 전에 후속 명령어가 해당 값을 읽으려 할 때 발생하는 의존성 충돌.
- **포워딩(Forwarding)**: 레지스터 기록 단계(WB)를 기다리지 않고 ALU 출력 또는 메모리 버퍼의 결과를 후속 명령어의 실행 입력(EX)으로 직접 전달하는 우회 기법.
- **파이프라인 플러시(Pipeline Flush)**: 분기 오예측이나 인터럽트 발생 시 잘못 진입된 파이프라인 단계 내 명령어들을 NOP 처리하여 무효화하고 파이프라인을 비우는 동작.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **데이터 해저드**로 인해 후속 명령어가 오래된 값 참조 | **포워딩** 경로 추가와 불가피한 구간의 스톨 삽입 | 잘못된 피연산자 사용 차단 |
| 분기 판정 지연으로 잘못된 명령어가 이미 진입 | 분기 확정 시점에 **파이프라인 플러시** 수행 | 잘못된 실행 경로의 결과 기록 방지 |
| 인출과 데이터 접근이 **버스**를 동시에 요구해 전송 지연 | 버스 중재 규칙 수립과 명령어·데이터 경로 분리 | 공유 경로 대기 시간 감소 |

#### 한줄 요약
- 성능을 깎는 것은 연산 속도가 아니라 값이 준비되기를 기다리는 시간이며, 대책은 모두 그 대기를 없애거나 감추는 방향으로 모인다.

## Ⅶ. 결론

- 저전력은 **단일 사이클**, 고성능 범용은 **파이프라인·비순서 마이크로아키텍처** 선택

#### 한줄 요약
- CPU 구성은 부품 이름을 외우는 문제가 아니라 제어·연산·저장·전달 책임을 어느 단위로 쪼개 대기 시간을 감출지 정하는 설계 문제이다.
