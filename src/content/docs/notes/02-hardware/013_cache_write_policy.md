## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: CPU 쓰기 연산 시 캐시와 주 메모리 간 데이터 반영 시점 및 블록 할당을 결정하는 메모리 제어 기법.
- **즉시 쓰기(Write-Through)**: 캐시 갱신과 동시에 주 메모리에도 데이터를 즉시 기록하여 일관성을 유지하는 방식.
- **후기입(Write-Back)**: 캐시만 먼저 갱신하고 수정된 블록이 교체될 때 하위 메모리에 일괄 기록하는 방식.
- **버스 대역폭(Bus Bandwidth)**: 프로세서와 주 메모리 간 버스 선로에서 단위 시간당 전송 가능한 최대 데이터 용량.
- **데이터 불일치(Data Inconsistency)**: 동일 주소의 데이터가 캐시와 주기억장치 간 서로 다른 값을 갖는 비정합성 상태.

</details>

- 정의/개념: CPU 쓰기 시 메모리 반영 시점에 따라 **즉시 쓰기**와 **후기입**으로 구분하는 메모리 제어 기법
- 배경/필요성: 모든 쓰기를 즉시 반영하면 **버스 대역폭**이 소진되고, 반영을 늦추면 최신 사본이 캐시에만 존재해 **데이터 불일치** 구간이 생김

#### 한줄 요약
- 두 정책의 차이는 속도가 아니라 최신 값이 어디에 있다고 약속하느냐이며, 그 약속이 DMA·전원 장애 같은 캐시 바깥 사건의 처리 방식을 통째로 바꾼다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 캐시 라인이 수정돼 하위 계층에 아직 반영되지 않은 상태를 나타내는 비트.
- **쓰기 버퍼(Write Buffer)**: 즉시 쓰기 정책에서 하위 계층으로 보낼 쓰기 요청을 임시 보관해 코어 대기를 줄이는 버퍼.
- **쓰기 할당(Write Allocate)**: 캐시 쓰기 미스 시 해당 블록을 캐시로 반입한 뒤 갱신하는 정책; 후기입과 조합.
- **쓰기 비할당(No-Write Allocate)**: 캐시 쓰기 미스 시 캐시 반입 없이 하위 계층으로 직접 쓰는 정책; 즉시 쓰기와 조합.

</details>

- 즉시 쓰기: 쓰기 적중 시 **쓰기 버퍼**를 통한 비동기 전송으로 코어 대기 시간 단축
- 후기입: **더티 비트**로 변경 상태를 추적하고 라인 교체 시에만 일괄 전송하여 버스 대역폭 절감
- 쓰기 할당은 후기입, **쓰기 비할당**은 즉시 쓰기와 주로 조합하되 독립 선택 가능

#### 한줄 요약
- 후기입의 이득은 쓰기 횟수가 아니라 같은 라인을 몇 번 다시 쓰느냐에 비례하므로, 재기록이 없는 스트리밍 쓰기에서는 두 정책의 대역폭이 같아진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하위 메모리 계층(Lower Memory Level)**: 현재 캐시보다 느리고 용량이 큰 다음 저장 계층.
- **캐시 정리(Cache Clean)**: 더티 라인을 하위 계층에 기록해 최신 상태를 반영하는 동작.

</details>

```text
[캐시 쓰기 제어]
├─ 캐시 라인
│  └─ 더티 비트
├─ 쓰기 버퍼 (하위 계층 쓰기 대기)
├─ 쓰기 정책 제어
│  ├─ 즉시 쓰기 경로
│  └─ 후기입 경로
└─ 하위 메모리 계층
```

선의 의미: 가지(`├─`)는 소유 관계; 즉시 쓰기·후기입 경로는 동일 캐시 라인에서 분기하는 대안

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 저장 명령어의 데이터 갱신 보관 |
| **더티 비트** | 후기입 라인의 미반영 상태 표시 |
| **쓰기 버퍼** | 즉시 쓰기 요청의 비동기 보관을 통한 코어 대기 시간 단축 |
| 쓰기 정책 제어 | 적중·미스별 쓰기 경로(즉시/후기입·할당/비할당) 선택 |
| 하위 메모리 계층 | 전송된 최신 데이터 영구 보관 |

#### 한줄 요약
- 두 구성요소는 같은 목적을 서로 다른 시점에 수행하는데, **쓰기 버퍼**는 전송을 미루고 **더티 비트**는 전송 자체를 합쳐 없앤다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 교체할 라인이 더티 상태일 때 새 라인 적재 전 하위 계층에 기록하는 동작.
- **캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없어 하위 계층 접근이 필요한 상황.

</details>

```text
저장 명령어 실행
      │
      ├─ 캐시 적중
      │      │
      │      ├─ 1. 즉시 쓰기 적중 처리: 캐시 갱신 → 쓰기 버퍼 → 하위 계층 전송
      │      │
      │      └─ 2. 후기입 적중 및 더티 축출: 캐시 갱신 → 더티 비트 설정
      │                                                   │
      │                                         (캐시 라인 교체 시) 더티 축출 → 하위 계층 기록
      │
      └─ 캐시 미스
             │
             ├─ 쓰기 할당(후기입): 블록 반입 → 갱신 → 더티 비트
             │
             └─ 쓰기 비할당(즉시 쓰기): 하위 계층에 직접 쓰기
```

분기 결과: 즉시 쓰기는 매 쓰기에 고정 비용을 균등하게 물리고, 후기입은 대부분의 쓰기를 공짜로 처리하는 대신 **더티 축출**이 일어나는 순간에 비용을 몰아서 지불

#### 한줄 요약
- 후기입이 평균 성능에서 앞서는 대신 최악 지연에서는 불리하므로, 응답 시간 편차를 통제해야 하는 실시간 시스템은 평균이 나쁜 쪽을 고르기도 한다.

## Ⅴ. 종류 및 비교

| 쓰기 정책 | 즉시 쓰기 | 후기입 |
|:---|:---|:---|
| 적용 기준 | 하위 계층의 즉시 최신성 보장이 필요 | 같은 라인 재기록이 잦고 대역폭 절감이 우선 |
| 핵심 특징 | 적중 시마다 **쓰기 버퍼**를 경유하여 하위 계층 전송 | **더티 비트**로 변경을 기록하고 라인 교체 시 일괄 반영 |
| 한계 | 쓰기가 잦으면 버퍼 포화와 **버스 대역폭** 소진 | **데이터 불일치** 구간에서 DMA·전원 장애 시 손실 위험 |

#### 한줄 요약
- 선택 기준은 성능이 아니라 캐시 밖에서 그 데이터를 누가 언제 보느냐이며, 보는 주체가 CPU뿐이면 후기입이 이길 여지가 없다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-coherent DMA)**: 장치와 CPU 캐시 사이의 일관성을 하드웨어가 자동 보장하지 않는 DMA 방식.
- **캐시 무효화(Cache Invalidate)**: 캐시 사본을 폐기해 다음 접근에서 하위 계층 최신 데이터를 반입하게 하는 동작.
- **메모리 장벽(Memory Barrier)**: 메모리 접근 관찰 순서에 필요한 제약을 강제하는 명령어 또는 제어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기 요청 폭증으로 **쓰기 버퍼** 포화 | 버퍼 크기·배수 정책 측정 후 후기입 전환 검토 | 코어 대기 시간 단축 및 쓰기 트래픽 완화 |
| **비일관성 DMA** 환경에서 더티 라인이 장치에 미반영 | DMA 전 **캐시 정리** 수행 후 완료 시점에 **캐시 무효화** | CPU·장치의 최신 데이터 관찰 일치 |
| 전원 장애 전 후기입 데이터 손실 위험 | 지속성 도메인과 캐시 정리 순서 검증 | 데이터 내구성 보장 범위 명확화 |
| 다중 코어 쓰기 순서와 공유 데이터 불일치 | 동기화 지점에 **메모리 장벽** 적용 | 코어 간 관찰 순서 보장 |

#### 한줄 요약
- 네 문제 모두 캐시 안이 아니라 캐시 경계에서 발생하므로, 쓰기 정책 결정은 캐시 설계가 아니라 시스템 경계 설계에 속한다.

## Ⅶ. 결론

- 일반 캐시는 쓰기 지역성을 살리는 **후기입**을 우선하되, 장치·지속성 경계에서 하위 계층의 즉시 가시성이 필요하면 **즉시 쓰기** 또는 명시적 캐시 정리 적용

#### 한줄 요약
- 현대 시스템이 후기입을 기본으로 두면서도 **캐시 정리** 명령을 남겨 둔 이유는, 정책을 하나로 고르는 대신 경계에서만 뒤집을 수 있게 한 절충이기 때문이다.
