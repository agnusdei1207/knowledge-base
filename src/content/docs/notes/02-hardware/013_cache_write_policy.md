## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: 데이터 쓰기 연산 시 캐시 메모리와 하위 메모리에 데이터를 갱신하는 시점과 방식을 결정하는 일관성 정책이다.
- **쓰기 트래픽(Write Traffic)**: 캐시 계층에서 하위 메모리로 발생하는 쓰기 데이터 전송량 및 버스 대역폭 점유율이다.
- **더티 비트(Dirty Bit)**: 캐시 라인의 내용이 수정되어 하위 메모리와 불일치함을 나타내는 1비트 상태 플래그이다.

</details>

- 정의/개념: CPU가 캐시 메모리에 쓰기(Write) 연산을 수행할 때 하위 메모리(DRAM)로 데이터를 갱신하는 시점과 방식을 규정하는 캐시 쓰기 정책
- 배경/필요성: 즉시 갱신 시 발생하는 **메모리 버스 트래픽 과부하**와 지연 갱신 시 발생하는 **데이터 불일치 및 전원 차단 유실 위험** 절충

#### 한줄 요약

- 쓰기 데이터의 하위 메모리 동기화 시점을 제어하여 **대역폭과 일관성을 절충한다.**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쓰기 할당(Write Allocate)**: 쓰기 미스 발생 시 해당 블록을 먼저 캐시로 적재한 후 쓰기 연산을 수행하는 방식이다.
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 발생 시 캐시에 올리지 않고 메인 메모리에 직접 기록하는 방식이다.
- **쓰기 병합(Write Combining)**: 동일 캐시 라인에 대한 다수의 쓰기 요청을 모아 메모리로는 1회의 라인 단위로 일괄 전송하는 최적화이다.

</details>

- **쓰기 할당(Write Allocate)** 및 **쓰기 비할당(No-Write Allocate)** 미스 처리 정책과의 결합 운용
- **쓰기 지역성(Write Locality)**이 높을수록 **후기입(Write-Back)**의 **쓰기 병합**을 통한 버스 트래픽 대폭 절감
- 후기입 구조에서 **더티 비트(Dirty Bit)** 관리를 통한 축출 시점 선택적 메모리 갱신

#### 한줄 요약

- Write-Through는 **즉시 동기화**, Write-Back은 **더티 비트와 쓰기 병합**으로 대역폭을 절감한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **쓰기 버퍼(Write Buffer)**: Write-Through 방식에서 CPU가 메모리 쓰기 완료를 기다리지 않고 비동기로 진행하도록 큐잉하는 버퍼이다.

</details>

```text
[ 캐시 쓰기 정책 제어 구조 ]
 ├─ 즉시 쓰기 (Write-Through)
 │  ├─ 캐시 메모리 라인 갱신
 │  ├─ 쓰기 버퍼 (Write Buffer) 적재
 │  └─ 메인 메모리 (DRAM) 즉시 비동기 전송
 └─ 후기입 (Write-Back)
    ├─ 캐시 메모리 라인 갱신
    ├─ 더티 비트 (Dirty Bit = 1) 설정
    └─ 라인 축출 (Eviction) 시점에만 메인 메모리 전송
```

선의 의미: 즉시 쓰기(Write Buffer 경유 즉시 전송)와 후기입(Dirty Bit 설정 후 축출 시 전송)의 데이터 흐름 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 쓰기 정책 제어부 | 적용된 쓰기 정책에 따른 경로 선택 및 제어 |
| 더티 비트 | **후기입** 캐시 라인의 하위 계층 미반영 상태 표시 |
| 쓰기 버퍼 | 하위 계층 쓰기 요청의 비동기 큐잉 |
| 하위 메모리 계층 | **즉시 쓰기** 요청과 축출 라인의 최종 저장 |

#### 한줄 요약

- **쓰기 버퍼(Write Buffer)**와 **더티 비트(Dirty Bit)**를 활용하여 비동기 지연을 은닉한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 새로운 라인 적재 시 더티 비트가 설정된 기존 라인을 메인 메모리로 덮어쓰고 비우는 동작이다.

</details>

```text
[ 데이터 쓰기 연산 요청 (CPU Store) ]
                 │
                 ▼
          [ 캐시 적중 여부 확인 ]
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
 [ 즉시 쓰기 (WT) ]  [ 후기입 (WB) ]
       │                   │
       ▼                   ▼
 [ 캐시 갱신 ]       [ 캐시 갱신 ]
       │                   │
       ▼                   ▼
 [ 쓰기 버퍼 전송 ]   [ Dirty Bit = 1 설정 ]
       │                   │
       ▼                   ▼
 [ DRAM 즉시 반영 ]  [ 추후 축출 시 DRAM 반영 ]
```

**동작 원리**

1. **즉시 쓰기(Write-Through)**: 캐시 데이터를 수정하는 즉시 쓰기 버퍼에 엔트리를 추가하여 메인 메모리에 전송
2. **후기입(Write-Back)**: 캐시 데이터만 수정하고 Dirty 비트를 1로 마킹한 뒤 연산 즉시 완료
3. **더티 축출(Dirty Eviction)**: 캐시 미스로 인해 새로운 블록을 적재할 때, 교체 대상 라인이 Dirty 상태이면 메모리에 라이트백 후 교체
4. **캐시 플러시(Cache Flush)**: DMA 통신 전이나 전원 차단 시 Dirty 라인을 전수 강제 기록

#### 한줄 요약

- Write-Through는 **버퍼 즉시 전송**, Write-Back은 **더티 설정 후 라인 축출 시 일괄 전송**을 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Write-Through vs Write-Back**:
  - Write-Through: 캐시와 메모리에 동시 쓰기를 수행하여 구조가 단순하고 일관성 유지가 용이하다.
  - Write-Back: 캐시에만 쓰기 후 축출 시 반영하여 대역폭을 대폭 절감하고 고성능을 제공한다.

</details>

| 비교 항목 | 즉시 쓰기 (Write-Through) | 후기입 (Write-Back) |
|:---|:---|:---|
| 적용 기준 | 데이터 일관성이 절대적인 임베디드, L1 명령어/하위 캐시 | 대역폭 절감이 필수적인 고성능 CPU L1/L2/L3 캐시 |
| 핵심 특징 | 캐시 갱신과 동시에 메인 메모리 즉시 기록, No-Write Allocate | 캐시만 갱신 후 Dirty 설정, 축출 시점에 메모리 기록, Write Allocate |
| 한계 및 위험 | 빈번한 쓰기 시 메모리 버스 대역폭 포화 및 지연 | 캐시-메모리 간 일시적 불일치, 전원 차단 시 데이터 유실 위험 |

#### 한줄 요약

- Write-Through는 **즉각적 일관성**, Write-Back은 **쓰기 병합 및 대역폭 최적화**를 달성한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Cache Clean vs Invalidate**: DMA 송신 전 캐시의 더티 데이터를 메모리로 밀어내는 Clean, 수신 후 캐시 사본을 파기하는 Invalidate이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기의 연속 요청으로 인한 **버퍼 포화** 및 대기 발생 | **쓰기 버퍼** 용량 확장 및 시스템의 **후기입** 전환 적용 | 트래픽 병목 해소 및 프로세서 지연 방지 |
| 후기입 환경에서 예기치 않은 전원 손실로 **더티 데이터** 유실 | 플랫폼 지속성 도메인 확보 및 전원 종료 전 **캐시 플러시** | 완료된 쓰기의 영구적 보존 및 무결성 유지 |
| **비일관성 DMA** 장치가 최신 데이터를 관측하지 못하는 오류 | 송신 전 **캐시 정리**, 수신 직후 캐시 무효화 수행 | 프로세서와 외부 장치 간의 데이터 일관성 완벽 보장 |
| 다중 코어 환경에서 복잡한 쓰기 순서 교란 및 경합 발생 | **메모리 장벽** 명령어의 명시적 배치 및 동기화 | 코어 간 데이터 갱신 관측 순서 보장 |

#### 한줄 요약

- **쓰기 버퍼 확장·비휘발성 플러시·Clean/Invalidate·메모리 배리어**로 안정성을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NVDIMM 및 지속성 메모리**: Write-Back 캐시를 사용하더라도 전원 차단 시 슈퍼 커패시터를 이용해 DRAM 내용을 플래시로 백업하는 고신뢰 메모리 기술이다.

</details>

- 워크로드 특성 분석 기반 **고속 대역폭이 필요한 범용 프로세서는 Write-Back + Write Allocate 채택**

#### 한줄 요약

- **쓰기 지역성과 메모리 대역폭 한계**에 맞춰 최적 캐시 쓰기 정책을 결정한다.
