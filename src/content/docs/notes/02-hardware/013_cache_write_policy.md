## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: CPU가 메모리 쓰기(Store) 연산 수행 시 캐시 메모리와 주기억장치 간의 데이터 반영 시점 및 블록 할당 방식을 제어하는 규칙.
- **즉시 쓰기(Write-Through)**: 캐시 블록 갱신과 동시에 주기억장치(또는 하위 캐시)에도 데이터를 즉시 기록하여 계층 간 일관성을 상시 유지하는 쓰기 방식.
- **후기입(Write-Back)**: 쓰기 연산 시 캐시 블록만 먼저 갱신하고, 해당 블록이 캐시에서 축출(Eviction)될 때만 하위 메모리에 일괄 기록하는 쓰기 방식.
- **버스 대역폭(Bus Bandwidth)**: 프로세서와 메모리 서브시스템 간의 시스템 버스에서 단위 시간당 전송 가능한 최대 데이터 용량(Bytes/sec).
- **데이터 불일치(Data Inconsistency)**: 동일한 메모리 주소에 대해 캐시의 최신 수정 데이터와 주기억장치의 데이터가 서로 일치하지 않는 비정합성 상태.

</details>

- 정의/개념: CPU 쓰기 시 메모리 반영 시점에 따라 **즉시 쓰기** 및 **후기입**으로 구분하는 메모리 제어 기법
- 배경/필요성: 단일 고정 쓰기 방식으로는 **버스 대역폭 소진 또는 메모리 간 데이터 불일치 해결 불가**

#### 한줄 요약
- 두 정책의 차이는 속도가 아니라 최신 값이 어디에 있다고 약속하느냐이며, 그 약속이 DMA·전원 장애 같은 캐시 바깥 사건의 처리 방식을 통째로 바꾼다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 후기입(Write-Back) 정책에서 특정 캐시 라인이 CPU에 의해 수정되었으나 하위 메모리에는 아직 반영되지 않았음을 나타내는 1비트 상태 플래그.
- **쓰기 버퍼(Write Buffer)**: 즉시 쓰기(Write-Through) 정책에서 하위 메모리로 전송할 쓰기 데이터와 주소를 임시 큐잉하여 CPU의 대기 지연(Stall)을 방지하는 FIFO 버퍼.
- **쓰기 할당(Write Allocate)**: 쓰기 미스 발생 시 하위 메모리에서 해당 블록을 캐시로 먼저 인출(Fetch)한 후 쓰기 연산을 수행하는 정책(주로 Write-Back과 조합).
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 발생 시 블록을 캐시로 가져오지 않고 하위 메모리에 직접 기록하는 정책(주로 Write-Through와 조합).

</details>

- 즉시 쓰기: 쓰기 적중 시 **쓰기 버퍼** 활용 통한 비동기 전송으로 코어 대기 시간 단축
- 후기입: **더티 비트** 기반 변경 상태를 추적하고 라인 교체 시에만 일괄 전송하여 버스 대역폭 절감
- 쓰기 할당은 후기입, **쓰기 비할당은** 즉시 쓰기와 주로 조합하되 독립 선택 가능

#### 한줄 요약
- 후기입의 이득은 쓰기 횟수가 아니라 같은 라인을 몇 번 다시 쓰느냐에 비례하므로, 재기록이 없는 스트리밍 쓰기에서는 두 정책의 대역폭이 같아진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하위 메모리 계층(Lower Memory Level)**: 현재 참조 중인 캐시보다 용량이 크고 접근 속도가 느린 다음 단계의 기억장치 계층(L2/L3 캐시 또는 메인 메모리).
- **캐시 정리(Cache Clean)**: 더티(Dirty) 상태의 캐시 블록을 하위 메모리에 기록(Write-Back)하여 메모리 사본을 최신 상태로 동기화하는 동작.

</details>

```text
[캐시 쓰기 제어]
├─ 캐시 라인
│  └─ 더티 비트
├─ 쓰기 버퍼 (하위 계층 쓰기 대기)
├─ 쓰기 정책 제어
│  ├─ 즉시 쓰기 경로
│  └─ 후기입 경로
└─ 하위 메모리 계층
```

선의 의미: 가지(`├─`)는 소유 관계; 즉시 쓰기·후기입 경로는 동일 캐시 라인에서 분기하는 대안

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 저장 명령어의 데이터 갱신 보관 |
| **더티 비트** | 후기입 라인의 미반영 상태 표시 |
| **쓰기 버퍼** | 즉시 쓰기 요청의 비동기 보관을 통한 코어 대기 시간 단축 |
| 쓰기 정책 제어 | 적중·미스별 쓰기 경로(즉시/후기입·할당/비할당) 선택 |
| 하위 메모리 계층 | 전송된 최신 데이터 영구 보관 |

#### 한줄 요약
- 두 구성요소는 같은 목적을 서로 다른 시점에 수행하는데, **쓰기 버퍼는** 전송을 미루고 **더티 비트는** 전송 자체를 합쳐 없앤다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 캐시 교체 시 교체 대상으로 선정된 희생 라인이 더티 상태일 때, 새 블록을 적재하기 전 하위 메모리로 수정된 데이터를 강제 기록하는 동작.
- **캐시 미스(Cache Miss)**: CPU가 요청한 메모리 주소의 블록이 캐시에 유효하게 존재하지 않아 하위 메모리 접근이 필요한 상태.

</details>

```text
저장 명령어 실행
      │
      ├─ 캐시 적중
      │      │
      │      ├─ 1. 즉시 쓰기 적중 처리: 캐시 갱신 → 쓰기 버퍼 → 하위 계층 전송
      │      │
      │      └─ 2. 후기입 적중 및 더티 축출: 캐시 갱신 → 더티 비트 설정
      │                                                   │
      │                                         (캐시 라인 교체 시) 더티 축출 → 하위 계층 기록
      │
      └─ 캐시 미스
             │
             ├─ 쓰기 할당(후기입): 블록 반입 → 갱신 → 더티 비트
             │
             └─ 쓰기 비할당(즉시 쓰기): 하위 계층에 직접 쓰기
```

분기 결과: 즉시 쓰기는 매 쓰기에 고정 비용을 균등하게 물리고, 후기입은 대부분의 쓰기를 공짜로 처리하는 대신 **더티 축출이** 일어나는 순간에 비용을 몰아서 지불

#### 한줄 요약
- 후기입이 평균 성능에서 앞서는 대신 최악 지연에서는 불리하므로, 응답 시간 편차를 통제해야 하는 실시간 시스템은 평균이 나쁜 쪽을 고르기도 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **즉시 쓰기(Write-Through)**: 캐시와 하위 메모리를 동시 갱신하여 데이터 일관성을 상시 유지하는 방식.
- **후기입(Write-Back)**: 캐시만 우선 갱신하고 교체 시점에 하위 메모리에 일괄 기록하여 버스 대역폭을 절감하는 방식.

</details>

| 쓰기 정책 | 즉시 쓰기 | 후기입 |
|:---|:---|:---|
| 적용 기준 | 하위 계층의 즉시 최신성 보장이 필요 | 같은 라인 재기록이 잦고 대역폭 절감이 우선 |
| 핵심 특징 | 적중 시마다 **쓰기 버퍼**를 경유하여 하위 계층 전송 | **더티 비트** 기반 변경을 기록하고 라인 교체 시 일괄 반영 |
| 한계 | 쓰기가 잦으면 버퍼 포화와 **버스 대역폭** 소진 | **데이터 불일치** 구간에서 DMA·전원 장애 시 손실 위험 |

#### 한줄 요약
- 선택 기준은 성능이 아니라 캐시 밖에서 그 데이터를 누가 언제 보느냐이며, 보는 주체가 CPU뿐이면 후기입이 이길 여지가 없다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-coherent DMA)**: 하드웨어 차원의 캐시 일관성을 지원하지 않아 DMA 입출력 전후에 소프트웨어의 명시적 캐시 정리 및 무효화가 요구되는 DMA 방식.
- **캐시 무효화(Cache Invalidate)**: 캐시 라인의 유효 비트(Valid Bit)를 해제하여 사본 데이터를 폐기하고, 다음 접근 시 하위 메모리의 최신 데이터를 강제 인출하도록 만드는 동작.
- **메모리 장벽(Memory Barrier)**: 컴파일러 및 CPU 파이프라인의 명령어 재정렬을 제한하여 메모리 읽기/쓰기 연산의 관찰 순서를 강제하는 하드웨어 동기화 명령어(Fence).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기 요청 폭증으로 **쓰기 버퍼** 포화 | 버퍼 크기·배수 정책 측정 후 후기입 전환 검토 | 코어 대기 시간 단축 및 쓰기 트래픽 완화 |
| **비일관성 DMA** 환경에서 더티 라인이 장치에 미반영 | DMA 전 **캐시 정리** 수행 후 완료 시점에 **캐시 무효화** | CPU·장치의 최신 데이터 관찰 일치 |
| 전원 장애 전 후기입 데이터 손실 위험 | 지속성 도메인과 캐시 정리 순서 검증 | 데이터 내구성 보장 범위 명확화 |
| 다중 코어 쓰기 순서와 공유 데이터 불일치 | 동기화 지점에 **메모리 장벽** 적용 | 코어 간 관찰 순서 보장 |

#### 한줄 요약
- 네 문제 모두 캐시 안이 아니라 캐시 경계에서 발생하므로, 쓰기 정책 결정은 캐시 설계가 아니라 시스템 경계 설계에 속한다.

## Ⅶ. 결론

- 대역폭 절감은 **후기입(Write-Back)**, 즉시 일관성은 **즉시 쓰기(Write-Through)** 선택

#### 한줄 요약
- 현대 시스템이 후기입을 기본으로 두면서도 **캐시 정리** 명령을 남겨 둔 이유는, 정책을 하나로 고르는 대신 경계에서만 뒤집을 수 있게 한 절충이기 때문이다.
