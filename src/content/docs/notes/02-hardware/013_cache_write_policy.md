## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: CPU가 메모리 쓰기(Store) 명령을 수행할 때 캐시 메모리와 하위 메모리(DRAM) 간의 데이터 반영 시점 및 블록 할당 방식을 통제하는 하드웨어 규칙.
- **즉시 쓰기(Write-Through)**: 캐시 라인 갱신과 동시에 하위 메모리(DRAM)에도 쓰기 데이터를 즉시 전송하여 계층 간 일관성을 상시 유지하는 방식.
- **후기입(Write-Back)**: 쓰기 연산 시 캐시 라인만 먼저 갱신하고 더티 비트를 설정한 후, 해당 블록이 캐시에서 축출(Eviction)될 때만 하위 메모리에 일괄 기록하는 방식.
- **시스템 버스 대역폭(Bus Bandwidth)**: 프로세서와 주기억장치 사이의 버스 선로에서 단위 시간당 전송 가능한 데이터 처리 용량.

</details>

- 정의/개념: CPU의 쓰기 데이터를 하위 메모리에 즉시 전송할지(Write-Through) 또는 축출 시점까지 캐시에 지연 보관할지(Write-Back)를 결정하는 **캐시 쓰기 관리 아키텍처**
- 배경/필요성: 단일 쓰기 방식으로는 **하위 메모리 버스 대역폭 소진(Write-Through 한계) 또는 전원 장애·DMA 시 데이터 불일치(Write-Back 한계)** 해결 불가

#### 한줄 요약
- 즉시 쓰기는 단순성과 상시 일관성을 확보하고, 후기입은 버스 대역폭을 획기적으로 절감한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 후기입 캐시 라인 헤더에 위치하여 해당 블록이 CPU에 의해 수정되었으나 하위 메모리에는 아직 반영되지 않았음을 나타내는 1비트 상태 플래그.
- **쓰기 버퍼(Write Buffer)**: 즉시 쓰기 캐시와 하위 버스 사이에 위치하여 메모리로 전송할 쓰기 데이터와 주소를 임시 큐잉함으로써 CPU 파이프라인 스톨을 방지하는 FIFO 버퍼.
- **쓰기 할당(Write Allocate)**: 쓰기 미스 발생 시 하위 메모리에서 해당 64B 블록을 캐시로 먼저 인출(Fetch)한 후 캐시에서 쓰기를 수행하는 정책(주로 Write-Back과 조합).
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 발생 시 블록을 캐시로 가져오지 않고 하위 메모리에 직접 기록하는 정책(주로 Write-Through와 조합).

</details>

- 즉시 쓰기: **쓰기 버퍼(Write Buffer)**를 활용하여 코어 대기 시간을 줄이며 하위 메모리와 캐시가 항상 동일한 최신 데이터 유지
- 후기입: 동일 블록에 대한 다수의 연속 쓰기를 캐시 내부에서 흡수하고 **더티 비트**로 추적하여 **시스템 버스 대역폭** 소모 극소화
- 미스 할당 조합: 후기입은 시간/공간 지역성을 활용하기 위해 **쓰기 할당(Write Allocate)**을 채택하고, 즉시 쓰기는 구조 단순화를 위해 **쓰기 비할당**을 주로 채택

#### 한줄 요약
- 즉시 쓰기는 쓰기 버퍼로 지연을 완화하고, 후기입은 더티 비트로 반복 쓰기를 흡수하여 대역폭을 아낀다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **캐시 정리(Cache Clean / Flush)**: 후기입 캐시에서 더티 상태의 라인을 하위 메모리에 강제 기록하여 메모리 데이터를 최신 상태로 동기화하는 동작.

</details>

```text
[CPU 코어 (Store 명령어 발생)]
               │
               ▼
[캐시 제어기 (Cache Controller)]
 ├─ [캐시 라인 어레이]
 │   ├─ 태그 (Tag)
 │   ├─ 상태 비트 (Valid, Dirty Bit) ─── 후기입 시 수정 여부 마킹
 │   └─ 64바이트 데이터 블록
 │
 ├─ [즉시 쓰기 경로 (Write-Through)] ──► [쓰기 버퍼 (FIFO Write Buffer)] ──► [하위 메모리 (DRAM)]
 │
 └─ [후기입 경로 (Write-Back)] ────────► 캐시 내 갱신 + Dirty=1 ──► (축출 시에만) 하위 메모리 일괄 기록
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 내부 구성 및 두 가지 독립된 쓰기 경로의 선택 관계

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **더티 비트 (Dirty Bit)**| 캐시 라인 헤더 | 캐시 수정 여부 표시 (0: Clean, 1: Dirty) | 후기입 캐시 필수 플래그 |
| **쓰기 버퍼 (Write Buffer)**| 캐시-버스 경계 | 즉시 쓰기 데이터의 비동기 큐잉으로 CPU 스톨 방지 | FIFO 큐 구조 |
| **캐시 제어기** | 캐시 서브시스템 | 적중/미스 및 쓰기 정책(WT/WB, WA/NWA) 총괄 제어 | 하드웨어 상태 머신 |
| **하위 메모리 계층** | L2/L3 캐시, DRAM | 최종 영구 데이터 보관 및 캐시 축출 블록 수용 | 시스템 버스로 연결 |

#### 한줄 요약
- 캐시 쓰기 서브시스템은 캐시 라인의 더티 비트와 외곽의 쓰기 버퍼를 통해 쓰기 연산의 지연과 버스 대역폭을 최적화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 캐시 교체 시 희생 라인의 Dirty 비트가 1일 때, 새 데이터를 적재하기 전에 수정된 블록을 하위 메모리에 먼저 기록하는 동작.

</details>

```text
1. CPU 코어의 Store (쓰기) 명령어 실행
                      │
                      ▼
2. 캐시 적중 여부 및 쓰기 정책 판정
   ┌──────────────────┴──────────────────┐
[ 캐시 적중 (Cache Hit) ]             [ 캐시 미스 (Cache Miss) ]
   │                                     │
   ├─ 즉시 쓰기 (Write-Through)          ├─ 후기입 + 쓰기 할당 (Write Allocate)
   │   └─ 캐시 갱신 ➔ 쓰기 버퍼 저장    │   └─ 하위 메모리에서 블록 인출 ➔ 캐시 적재 ➔ 쓰기 수행 + Dirty=1
   │       ➔ 비동기 메모리 전송          │
   │                                     └─ 즉시 쓰기 + 쓰기 비할당 (No-Write Allocate)
   └─ 후기입 (Write-Back)                    └─ 캐시 무시하고 하위 메모리에 직접 기록
       └─ 캐시만 갱신 + Dirty Bit=1
           │
           ▼
   (이후 라인 교체 시)
   더티 축출(Dirty Eviction) ➔ 하위 메모리 일괄 기록
```

분기 결과: **즉시 쓰기는** 매 쓰기마다 버스 전송이 발생하나 메모리가 항상 최신이며, **후기입은** 캐시 내에서 1클록 완료되나 축출 시 더티 기록 지연이 발생함

#### 한줄 요약
- 적중 시 즉시 쓰기는 쓰기 버퍼로 메모리에 동시 전송하고, 후기입은 캐시만 수정하고 더티 비트를 켜 두었다가 축출 시 메모리에 쓴다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 즉시 쓰기 (Write-Through) | 후기입 (Write-Back) |
|:---|:---|:---|
| 메모리 반영 시점 | **쓰기 연산 발생 즉시 실시간 전송** | **해당 캐시 라인이 축출(Eviction)되는 시점** |
| 버스 트랜잭션 빈도 | 매우 높음 (모든 쓰기 명령마다 버스 점유) | **매우 낮음 (동일 블록 다중 쓰기를 캐시에서 일괄 흡수)** |
| 하드웨어 구현 | **더티 비트 불필요, 구조 단순, 쓰기 버퍼 필수** | **라인별 더티 비트 및 축출 시 쓰기 로직 필수** |
| 데이터 일관성 | 상시 최신 상태 유지 (DMA/전원 장애에 안전) | 불일치 구간 존재 (소프트웨어 캐시 정리 필요) |
| 주요 적용처 | L1 I-Cache(불필요), 실시간 안전 임베디드 | **현대 CPU의 L1 Data, L2, L3 캐시 표준** |

#### 한줄 요약
- 즉시 쓰기는 단순성과 상시 일관성을 확보하고, 후기입은 버스 대역폭을 획기적으로 절감하여 현대 고성능 프로세서의 표준으로 사용된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-Coherent DMA)**: 하드웨어 일관성을 지원하지 않는 주변장치가 DMA로 메모리를 접근할 때 캐시와 불일치가 발생하는 현상.
- **메모리 배리어(Memory Barrier)**: 쓰기 버퍼 및 비순차 실행 파이프라인의 데이터 기록 순서를 동기화하는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 연속적인 즉시 쓰기로 인한 **쓰기 버퍼(Write Buffer)** 포화 및 코어 스톨 | **후기입(Write-Back) 정책으로 전환** 및 버퍼 심도 확장 | 버스 트랜잭션 80% 이상 절감 및 파이프라인 정체 해소 |
| 후기입 환경에서 DMA 전송 시 메모리에 더티 데이터 미반영 오류 | DMA 시작 전 **명시적 캐시 정리(Clean)** 및 완료 후 **무효화(Invalidate)** | CPU와 DMA 장치 간 데이터 무결성 보장 |
| 비순차 실행 코어에서 쓰기 버퍼 내 데이터의 관찰 순서 역전 | 동기화 지점에 **메모리 배리어(DMB/DSB)** 명령어 삽입 | 멀티스레드 간 메모리 기록 가시성 순서 보장 |

#### 한줄 요약
- 후기입 환경에서는 DMA 통신 전후의 명시적 캐시 정리와 멀티스레드 동기화를 위한 메모리 배리어 적용이 실무의 핵심이다.

## Ⅶ. 결론

- 고성능 범용 컴퓨팅에서는 **메모리 버스 대역폭 절감을 위해 후기입(Write-Back)과 쓰기 할당(Write Allocate) 조합을 L1/L2/L3 캐시에 표준 적용**하고, 주변장치 통신 및 전력 차단 환경에서는 **비일관성 DMA를 위한 캐시 정리(Clean/Invalidate) API와 메모리 배리어 동기화**를 체계화하는 메모리 서브시스템 아키텍처 확립

#### 한줄 요약
- 고성능 시스템은 대역폭 절감을 위해 후기입을 기본 채택하며, DMA 및 동기화 경계에서는 명시적 캐시 관리를 통해 무결성을 확보한다.
