## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: 저장 명령어 적중 때 캐시와 하위 계층을 갱신하는 시점과 방식을 정하는 정책입니다.
- **즉시 쓰기(Write-Through)**: 캐시 갱신과 함께 하위 계층 쓰기를 요청하는 정책입니다.
- **후기입(Write-Back)**: 캐시만 갱신하고 라인 교체 또는 정리 때 하위 계층에 쓰는 정책입니다.

</details>

- 정의/개념: 저장 데이터의 하위 계층 반영 시점을 정하는 **캐시 갱신 정책**
- 배경/필요성: 쓰기 대역폭과 최신 데이터 반영 시점의 절충

#### 한줄 요약

- 즉시 쓰기는 쓸 때마다 아래 저장소에도 바로 알리고, 후기입은 캐시에 모아 두었다가 자리를 비울 때 한꺼번에 알리는 방식입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 캐시 라인이 수정돼 하위 계층에 아직 반영되지 않았음을 나타내는 상태 비트입니다.
- **쓰기 버퍼(Write Buffer)**: 하위 계층으로 보낼 쓰기 요청을 임시로 보관해 코어 대기를 줄이는 버퍼입니다.
- **쓰기 할당(Write Allocate)**: 쓰기 미스 때 해당 블록을 캐시로 가져온 뒤 쓰는 정책입니다.
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 때 캐시에 가져오지 않고 하위 계층으로 직접 쓰는 정책입니다.

</details>

- 즉시 쓰기: 하위 계층 갱신과 **쓰기 버퍼 활용**
- 후기입: 더티 비트 기반의 **쓰기 병합**
- 미스 처리: 쓰기 할당과 **쓰기 비할당**의 별도 선택

#### 한줄 요약

- 즉시 쓰기는 최신 데이터를 아래 계층에 빨리 보이게 하고, 후기입은 같은 라인을 여러 번 바꿔도 전송을 한 번으로 묶어 대역폭을 아낍니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하위 메모리 계층(Lower Memory Level)**: 현재 캐시보다 느리고 큰 다음 저장 계층입니다.
- **캐시 정리(Cache Clean)**: 더티 라인을 하위 계층에 기록해 최신 데이터를 반영하는 동작입니다.

</details>

```text
[캐시 쓰기 제어]
├─ 캐시 라인
├─ 더티 비트
├─ 쓰기 버퍼
├─ 쓰기 정책 제어
└─ 하위 메모리 계층
```

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 저장 명령어의 데이터 갱신 |
| 더티 비트 | 후기입 라인의 미반영 상태 표시 |
| 쓰기 버퍼 | 즉시 쓰기 요청의 비동기 보관 |
| 쓰기 정책 제어 | 적중·미스별 쓰기 경로 선택 |
| 하위 메모리 계층 | 전송된 최신 데이터 보관 |

#### 한줄 요약

- 쓰기 정책은 캐시에 쓴 값을 아래 계층으로 보낼 때까지, 더티 비트와 쓰기 버퍼로 변경 상태와 전송 대기를 관리합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 교체할 라인이 더티일 때 새 라인을 넣기 전 하위 계층에 기록하는 동작입니다.
- **캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없어 하위 계층 접근이 필요한 상황입니다.

</details>

```text
[1. 저장 요청과 적중 확인]
          │
          ▼
[2. 캐시 라인 갱신]
          │
          ├─ 즉시 쓰기
          │       │
          │       ▼
          │  [3. 쓰기 버퍼·하위 계층 전송]
          │
          └─ 후기입
                  │
                  ▼
             [3. 더티 비트 설정]
                  │
                  ▼
             [4. 축출·정리 시 하위 계층 기록]
```

동작 원리:

1. 저장 요청과 적중 확인: 대상 라인의 캐시 존재 여부 판정
2. 캐시 라인 갱신: 저장 데이터를 캐시 라인에 기록
3. 쓰기 버퍼·하위 계층 전송 또는 더티 비트 설정: 정책별 반영 시점 결정
4. 축출·정리 시 하위 계층 기록: 후기입 더티 라인의 최신 값 반영

#### 한줄 요약

- 같은 캐시 갱신이라도 즉시 쓰기는 전송을 바로 시작하고, 후기입은 더티 표시만 남겼다가 캐시 라인이 나갈 때 전송합니다.

## Ⅴ. 종류 및 비교

| 쓰기 정책 | 즉시 쓰기 | 후기입 |
|:---|:---|:---|
| 적용 기준 | 단순한 하위 계층 반영이 우선 | 쓰기 지역성과 대역폭 절감이 우선 |
| 핵심 특징 | 적중마다 하위 계층 쓰기 요청 | 더티 라인의 축출·정리 시 반영 |
| 한계 | 빈번한 쓰기에서 트래픽 증가 | 더티 데이터 관리와 반영 시점 제약 |

#### 한줄 요약

- 바로 아래 저장소까지 맞춰야 하면 즉시 쓰기, 같은 데이터를 여러 번 고쳐 버스 사용을 줄여야 하면 후기입이 맞습니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-coherent DMA)**: 장치와 CPU 캐시 사이의 데이터 일관성을 하드웨어가 자동으로 맞추지 않는 DMA 방식입니다.
- **캐시 무효화(Cache Invalidate)**: 캐시 사본을 폐기해 다음 접근에서 최신 데이터를 다시 가져오게 하는 동작입니다.
- **메모리 장벽(Memory Barrier)**: 메모리 접근의 관찰 순서에 필요한 제약을 두는 명령어 또는 제어입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기 요청이 많아 버퍼 포화 | 버퍼 크기·배수 정책 측정과 후기입 검토 | 코어 대기와 쓰기 트래픽 완화 |
| 후기입 더티 데이터가 장치에 보이지 않음 | DMA 전 캐시 정리·후 무효화 적용 | CPU·장치의 최신 데이터 관찰 일치 |
| 전원 장애 전 최신 데이터 반영 불명확 | 지속성 도메인과 캐시 정리 순서 검증 | 데이터 내구성 보장 범위 명확화 |
| 다중 코어 쓰기 순서가 공유 데이터와 불일치 | 동기화 지점에 메모리 장벽 적용 | 코어 간 관찰 순서 보장 |

#### 한줄 요약

- 쓰기 정책은 캐시 안에서만 끝나지 않으며, 장치와 공유하는 버퍼나 전원 장애 뒤에도 누가 최신 값을 볼지까지 정해야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **쓰기 지역성(Write Locality)**: 같은 데이터 또는 가까운 데이터를 반복해서 쓰는 접근 성질입니다.

</details>

- **쓰기 지역성**과 대역폭 제약이 크면 후기입을, 즉시 하위 계층 반영이 우선이면 즉시 쓰기를 선택하고 미스 할당·DMA·지속성 요구까지 함께 검증

#### 한줄 요약

- 어떤 정책이 더 좋다고 고정할 수 없으며, 데이터를 자주 다시 쓰는지와 다른 장치·장애 상황에서도 바로 최신 값이 필요한지로 선택해야 합니다.
