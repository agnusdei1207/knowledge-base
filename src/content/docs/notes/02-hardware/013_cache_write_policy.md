## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: 저장 명령어 적중 시 캐시와 하위 계층을 갱신하는 시점과 방식을 결정하는 정책.
- **즉시 쓰기(Write-Through)**: 캐시 갱신과 동시에 하위 계층 쓰기 요청을 발행하는 정책.
- **후기입(Write-Back)**: 캐시만 갱신하고 라인 교체·정리 시점에 하위 계층에 기록하는 정책.

</details>

- 정의/개념: 저장 데이터의 하위 계층 반영 시점을 즉시 또는 지연으로 결정하는 **캐시 갱신 정책**
- 배경/필요성: 쓰기 버스 대역폭 소비와 하위 계층 최신성 보장의 절충

#### 한줄 요약
- 즉시 쓰기는 쓸 때마다 하위 저장소에 바로 알리고, 후기입은 캐시에 모아 두었다가 라인이 나갈 때 한 번에 전송해 대역폭을 절약한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 캐시 라인이 수정돼 하위 계층에 아직 반영되지 않은 상태를 나타내는 비트.
- **쓰기 버퍼(Write Buffer)**: 즉시 쓰기 정책에서 하위 계층으로 보낼 쓰기 요청을 임시 보관해 코어 대기를 줄이는 버퍼.
- **쓰기 할당(Write Allocate)**: 쓰기 미스 시 해당 블록을 캐시로 반입한 뒤 갱신하는 정책; 후기입과 조합.
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 시 캐시 반입 없이 하위 계층으로 직접 쓰는 정책; 즉시 쓰기와 조합.

</details>

- 즉시 쓰기: 적중마다 **쓰기 버퍼**로 하위 계층 전송을 비동기화해 코어 대기 감소
- 후기입: **더티 비트**로 변경 추적·라인 교체 시에만 전송해 쓰기 대역폭 절감
- 미스 처리: **쓰기 할당**(후기입)·**쓰기 비할당**(즉시 쓰기)을 독립 선택

#### 한줄 요약
- 즉시 쓰기는 매번 전송해 하위 계층을 최신 상태로 유지하고, 후기입은 같은 라인을 여러 번 고쳐도 전송을 한 번으로 묶어 대역폭을 아낀다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하위 메모리 계층(Lower Memory Level)**: 현재 캐시보다 느리고 용량이 큰 다음 저장 계층.
- **캐시 정리(Cache Clean)**: 더티 라인을 하위 계층에 기록해 최신 상태를 반영하는 동작.

</details>

```text
[캐시 쓰기 제어]
├─ 캐시 라인
│  └─ 더티 비트
├─ 쓰기 버퍼 (즉시 쓰기 전용)
├─ 쓰기 정책 제어
│  ├─ 즉시 쓰기 경로
│  └─ 후기입 경로
└─ 하위 메모리 계층
```

선의 의미: 가지(`├─`)는 소유 관계; 즉시 쓰기·후기입 경로는 동일 캐시 라인에서 분기하는 대안

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 저장 명령어의 데이터 갱신 보관 |
| **더티 비트** | 후기입 라인의 미반영 상태 표시 |
| **쓰기 버퍼** | 즉시 쓰기 요청의 비동기 보관으로 코어 대기 감소 |
| 쓰기 정책 제어 | 적중·미스별 쓰기 경로(즉시/후기입·할당/비할당) 선택 |
| 하위 메모리 계층 | 전송된 최신 데이터 영구 보관 |

#### 한줄 요약
- 더티 비트가 후기입 상태를 기억하고, 쓰기 버퍼가 즉시 쓰기 요청을 이어받아 코어와 하위 계층을 분리한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 교체할 라인이 더티 상태일 때 새 라인 적재 전 하위 계층에 기록하는 동작.
- **캐시 미스(Cache Miss)**: 요청한 데이터가 캐시에 없어 하위 계층 접근이 필요한 상황.

</details>

```text
저장 명령어 실행
      │
      ├─ 캐시 적중
      │      │
      │      ├─ 즉시 쓰기: 캐시 갱신 → 쓰기 버퍼 → 하위 계층 전송
      │      │
      │      └─ 후기입: 캐시 갱신 → 더티 비트 설정
      │                              │
      │                    (교체 시) 더티 축출 → 하위 계층 기록
      │
      └─ 캐시 미스
             │
             ├─ 쓰기 할당(후기입): 블록 반입 → 갱신 → 더티 비트
             │
             └─ 쓰기 비할당(즉시 쓰기): 하위 계층에 직접 쓰기
```

**동작 원리**

1. **즉시 쓰기 적중**: 캐시 라인 갱신과 동시에 쓰기 버퍼에 하위 계층 전송 요청 등록
2. **후기입 적중**: 캐시 라인만 갱신하고 더티 비트 설정; 교체 시 더티 축출로 하위 계층 기록
3. **미스 처리**: 즉시 쓰기는 쓰기 비할당으로 직접 전송, 후기입은 쓰기 할당으로 반입 후 갱신

#### 한줄 요약
- 같은 쓰기 명령이라도 즉시 쓰기는 전송을 바로 시작하고, 후기입은 더티 표시만 남겼다가 라인이 나갈 때 전송한다.

## Ⅴ. 종류 및 비교

| 쓰기 정책 | 즉시 쓰기 | 후기입 |
|:---|:---|:---|
| 적용 기준 | 하위 계층 최신성 즉시 보장 필요 | **쓰기 지역성** 높고 대역폭 절감 우선 |
| 핵심 특징 | 적중마다 **쓰기 버퍼** 경유 하위 계층 전송 | **더티 비트**로 지연 전송·라인 교체 시 반영 |
| 한계 | 빈번한 쓰기에서 버퍼 포화·트래픽 증가 | 더티 데이터의 DMA·장애 시 미반영 위험 |

#### 한줄 요약
- 하위 계층까지 즉시 맞춰야 하면 즉시 쓰기, 같은 데이터를 자주 고쳐 버스를 아껴야 하면 후기입이 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-coherent DMA)**: 장치와 CPU 캐시 사이의 일관성을 하드웨어가 자동 보장하지 않는 DMA 방식.
- **캐시 무효화(Cache Invalidate)**: 캐시 사본을 폐기해 다음 접근에서 하위 계층 최신 데이터를 반입하게 하는 동작.
- **메모리 장벽(Memory Barrier)**: 메모리 접근 관찰 순서에 필요한 제약을 강제하는 명령어 또는 제어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기 요청 폭증으로 **쓰기 버퍼** 포화 | 버퍼 크기·배수 정책 측정 후 후기입 전환 검토 | 코어 대기·쓰기 트래픽 완화 |
| 후기입 **더티 비트** 데이터가 DMA 장치에 미반영 | DMA 전 캐시 정리(Clean)·이후 **캐시 무효화** | CPU·장치의 최신 데이터 관찰 일치 |
| 전원 장애 전 후기입 데이터 손실 위험 | 지속성 도메인과 캐시 정리 순서 검증 | 데이터 내구성 보장 범위 명확화 |
| 다중 코어 쓰기 순서와 공유 데이터 불일치 | 동기화 지점에 **메모리 장벽** 적용 | 코어 간 관찰 순서 보장 |

#### 한줄 요약
- 쓰기 정책은 캐시 안에서만 끝나지 않으며, DMA 장치와 전원 장애 시에도 누가 최신 값을 볼지까지 설계해야 한다.

## Ⅶ. 결론

- **쓰기 지역성**과 대역폭 제약이 크면 **후기입**·쓰기 할당을, 즉시 하위 계층 반영이 필수이면 즉시 쓰기를 선택하고 DMA·장애·멀티코어 순서 요구까지 함께 검증

#### 한줄 요약
- 어떤 정책이 항상 좋다고 고정할 수 없으며, 데이터를 자주 다시 쓰는지와 DMA·장애 시에도 즉시 최신 값이 필요한지로 선택한다.
