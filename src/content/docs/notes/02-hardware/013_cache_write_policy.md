## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: CPU가 메모리 쓰기(Store) 명령을 수행할 때 캐시 메모리와 하위 메모리(DRAM) 간의 데이터 반영 시점 및 블록 할당 방식을 통제하는 하드웨어 규칙.
- **즉시 쓰기(Write-Through)**: 캐시 라인 갱신과 동시에 하위 메모리(DRAM)에도 쓰기 데이터를 즉시 전송하여 계층 간 일관성을 상시 유지하는 방식.
- **후기입(Write-Back)**: 쓰기 연산 시 캐시 라인만 먼저 갱신하고 더티 비트를 설정한 후, 해당 블록이 캐시에서 축출(Eviction)될 때만 하위 메모리에 일괄 기록하는 방식.
- **시스템 버스 대역폭(Bus Bandwidth)**: 프로세서와 주기억장치 사이의 버스 선로에서 단위 시간당 전송 가능한 데이터 처리 용량.

</details>

- 정의/개념: 프로세서의 메모리 쓰기 명령 시점에 하위 메모리를 즉시 갱신하는 **즉시 쓰기**와 블록 축출 시점에 일괄 기록하는 **후기입**으로 구분되는 캐시-주기억장치 간 데이터 동기화 정책
- 배경/필요성: 프로세서의 빈번한 쓰기 연산마다 저속의 외부 DRAM을 직접 갱신할 때 발생하는 **시스템 버스 대역폭** 포화 및 파이프라인 스톨 오버헤드를 완화하기 위해 차별화된 쓰기 반영 시점 제어 메커니즘 필수화

#### 한줄 요약
- 즉시 쓰기는 단순성과 상시 일관성을 확보하고, 후기입은 버스 대역폭을 획기적으로 절감한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **더티 비트(Dirty Bit)**: 후기입 캐시 라인 헤더에 위치하여 해당 블록이 CPU에 의해 수정되었으나 하위 메모리에는 아직 반영되지 않았음을 나타내는 1비트 상태 플래그.
- **쓰기 버퍼(Write Buffer)**: 즉시 쓰기 캐시와 하위 버스 사이에 위치하여 메모리로 전송할 쓰기 데이터와 주소를 임시 큐잉함으로써 CPU 파이프라인 스톨을 방지하는 FIFO 버퍼.
- **쓰기 할당(Write Allocate)**: 쓰기 미스 발생 시 하위 메모리에서 해당 64B 블록을 캐시로 먼저 인출(Fetch)한 후 캐시에서 쓰기를 수행하는 정책(주로 Write-Back과 조합).
- **쓰기 비할당(No-Write Allocate)**: 쓰기 미스 발생 시 블록을 캐시에 올리지 않고 하위 메모리에 직접 기록하는 정책(주로 Write-Through와 조합).

</details>

- 대역폭 절감 및 지연 은닉: **후기입** 적용 시 캐시 라인 축출 시점에만 일괄 기록하여 버스 대역폭 낭비 방지
- 상시 무결성과 단순성: **즉시 쓰기** 적용 시 하위 메모리와 상시 일치하여 비일관성 DMA 환경에서 안전성 확보
- 할당 정책 연계: 미스 발생 시 **쓰기 할당**과 **쓰기 비할당** 정책을 결합하여 캐시 오염 및 인출 오버헤드 통제

#### 한줄 요약
- 후기입은 대역폭을 절감하고, 즉시 쓰기는 상시 일관성을 유지하며, 쓰기 미스 시 할당 여부로 오버헤드를 제어한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **캐시 제어기(Cache Controller)**: 캐시 메모리의 읽기/쓰기 동작, 태그 비교, 적중 판정, 상태 비트 갱신을 전담하는 하드웨어 유닛.
- **캐시 플러시(Cache Flush)**: 후기입 캐시의 더티 라인을 하위 메모리에 강제로 기록하고 유효 비트를 무효화하는 하드웨어/소프트웨어 동작.

</details>

```text
[캐시 쓰기 서브시스템]
  │
  ├─ [캐시 제어기] (적중·미스 판정 및 상태 전이)
  │
  ├─ [캐시 라인 블록]
  │     ├─ [태그 및 유효 비트] (적중 판정)
  │     └─ [더티 비트 (Dirty)] (후기입 수정 추적)
  │
  ├─ [FIFO 쓰기 버퍼] (즉시 쓰기 비동기 큐잉)
  │
  └─ [하위 메모리 계층] (L2/L3 캐시 및 메인 DRAM)
```

선의 의미: 캐시 쓰기 정책 제어기, 메모리 블록, 쓰기 버퍼 및 하위 메모리의 계층 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 더티 비트 | 캐시 라인 데이터 수정 여부를 보관하며 축출 시 **되쓰기(Write-Back)** 판정 |
| 쓰기 버퍼 | 즉시 쓰기 데이터를 **FIFO 큐잉**하여 CPU 파이프라인의 버스 대기 스톨 방지 |
| 캐시 제어기 | 쓰기 적중·미스 판정 및 정책에 따른 **상태 전이** 총괄 제어 |
| 하위 메모리 계층 | 쓰기 버퍼 데이터 및 후기입 축출 블록의 **최종 영구 보관** 담당 |

#### 한줄 요약
- 캐시 쓰기 서브시스템은 캐시 라인의 더티 비트와 외곽의 쓰기 버퍼를 통해 쓰기 연산의 지연과 버스 대역폭을 최적화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 캐시 교체 시 희생 라인의 Dirty 비트가 1일 때, 새 데이터를 적재하기 전에 수정된 블록을 하위 메모리에 먼저 기록하는 동작.

</details>

```text
[CPU 코어 Store 쓰기 명령어 실행]
                  │
                  ▼
       1. 적중·쓰기 정책 판정
   ┌──────────────┴──────────────┐
(캐시 적중: Cache Hit)        (캐시 미스: Cache Miss)
   │                             │
   ├─ 즉시 쓰기:                 ├─ 후기입 + 쓰기 할당:
   │  2. 캐시 갱신 및 쓰기버퍼   │  4. 블록 인출 후 캐시 적재 (Dirty=1)
   │                             │
   └─ 후기입:                    └─ 즉시 쓰기 + 쓰기 비할당:
      3. 캐시만 갱신 (Dirty=1)      하위 메모리 직접 기록 (캐시 미적재)
   │                             │
   └──────────────┬──────────────┘
                  │
                  ▼
       5. 더티 축출 및 최종 반영
```

분기 결과: 즉시 쓰기는 **상시 일관성 확보**, 후기입은 **버스 대역폭 최소화**

**동작 원리**

1. **적중·쓰기 정책 판정**: CPU Store 요청 시 주소 태그를 비교하여 적중 여부를 판별하고 구성된 쓰기 정책에 따라 분기함
2. **즉시 쓰기 적중 처리**: 캐시 라인을 갱신함과 동시에 쓰기 버퍼에 주소와 데이터를 큐잉하여 하위 메모리로 즉시 전송함
3. **후기입 적중 처리**: 하위 메모리 버스 트래픽을 발생시키지 않고 캐시 라인 데이터만 갱신한 뒤 해당 라인의 더티 비트를 1로 세팅함
4. **쓰기 미스 처리**: 쓰기 할당 정책에서는 하위 메모리에서 해당 블록을 캐시로 반입 후 쓰기를 실행하며, 쓰기 비할당에서는 하위 메모리에 직접 기록함
5. **더티 축출 및 최종 반영**: 후기입 캐시에서 교체 발생 시 희생 라인의 더티 비트가 1이면 수정된 블록을 하위 메모리에 일괄 라이트백한 후 새 블록을 적재함

#### 한줄 요약
- 적중 시 즉시 쓰기는 쓰기 버퍼로 메모리에 동시 전송하고, 후기입은 캐시만 수정하고 더티 비트를 켜 두었다가 축출 시 메모리에 쓴다.

## Ⅴ. 종류 및 비교

| 캐시 쓰기 정책 | 즉시 쓰기 (Write-Through) | 후기입 (Write-Back) |
|:---|:---|:---|
| 적용 기준 | **상시 데이터 일관성** 및 단순 제어 요구 | **버스 대역폭 절감** 및 고성능 연산 요구 |
| 핵심 특징 | 쓰기 즉시 하위 메모리 전송 및 **쓰기 버퍼** 완충 | 캐시 라인만 우선 갱신 후 **축출 시점 일괄 반영** |
| 한계 | 빈번한 버스 점유로 **대역폭 낭비** 및 스톨 위험 | 메모리 불일치 구간 존재에 따른 **동기화 오버헤드** 발생 |

#### 한줄 요약
- 즉시 쓰기는 단순성과 상시 일관성을 확보하고, 후기입은 버스 대역폭을 획기적으로 절감하여 현대 고성능 프로세서의 표준으로 사용된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-Coherent DMA)**: 하드웨어 일관성을 지원하지 않는 주변장치가 DMA로 메모리를 접근할 때 캐시와 불일치가 발생하는 현상.
- **메모리 배리어(Memory Barrier)**: 쓰기 버퍼 및 비순차 실행 파이프라인의 데이터 기록 순서를 동기화하는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 연속적인 즉시 쓰기로 인한 쓰기 버퍼 포화 및 파이프라인 스톨 | **후기입 정책** 전환 및 버퍼 심도 확장 | 버스 트랜잭션 대폭 절감 및 파이프라인 정체 해소 |
| 후기입 환경에서 DMA 전송 시 메인 메모리 데이터 불일치 | DMA 전송 전후 **캐시 플러시 및 무효화** 수행 | CPU와 주변 DMA 장치 간 메모리 무결성 보장 |
| 비순차 실행 코어에서 쓰기 버퍼 데이터 관찰 순서 역전 | 동기화 임계 지점에 **메모리 배리어** 삽입 | 멀티스레드 간 메모리 기록 가시성 및 실행 순서 보장 |

#### 한줄 요약
- 후기입 환경에서는 DMA 통신 전후의 명시적 캐시 정리와 멀티스레드 동기화를 위한 메모리 배리어 적용이 실무의 핵심이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL(Compute Express Link)**: 호스트 프로세서와 가속기·메모리 확장 장치 간에 캐시 일관성(CXL.cache)과 메모리 풀링(CXL.mem)을 지원하는 PCIe 기반 고속 인터커넥트 표준.

</details>

- 현대 고성능 프로세서 L1/L2/L3 캐시는 **후기입(Write-Back)·쓰기 할당(Write-Allocate)** 조합이 표준으로 정착되었으며, 차세대 이기종 가속기·다중 노드 환경에서는 **CXL 기반 하드웨어 캐시 일관성 인터커넥트**와 결합하여 라이트백 동기화 오버헤드를 하드웨어 계층에서 은닉하고 있어, 비일관성 I/O 구간의 명시적 캐시 클린·무효화 비용을 최소화하는 버퍼 경계 설계

#### 한줄 요약
- 고성능 시스템은 대역폭 절감을 위해 후기입을 기본 채택하며, DMA 및 동기화 경계에서는 명시적 캐시 관리를 통해 무결성을 확보한다.
