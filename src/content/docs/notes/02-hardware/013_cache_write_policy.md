## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 쓰기 정책(Cache Write Policy)**: 데이터 쓰기 연산을 수행할 때 캐시 메모리와 하위 메모리에 데이터를 갱신하는 시점과 방식을 결정하는 메모리 일관성 정책이다.
- **쓰기 트래픽(Write Traffic)**: 캐시 계층에서 하위 메모리로 발생하는 쓰기 데이터 전송량 및 대역폭 점유율이다.
- **미반영 위험(Write-Back Risk)**: 캐시에만 최신 데이터가 남아있을 때 전원 차단 시 데이터가 유실될 수 있는 안정성 위험이다.

</details>

- 정의: 데이터 쓰기 연산 발생 시 캐시 메모리와 하위 계층 간의 데이터 업데이트 시점을 제어하는 **캐시 쓰기 정책**
- 배경: 즉시 반영에 따른 **쓰기 트래픽** 급증과 지연 반영에 따른 **미반영 위험** 간의 상충 관계를 최적화하기 위함

#### 한줄 요약

- 쓰기 데이터의 하위 계층 동기화 시점을 제어하여 대역폭 절감과 데이터 일관성을 절충하는 메모리 관리 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쓰기 할당(Write Allocate)**: 쓰기 실패 시 해당 메모리 블록을 캐시로 먼저 적재한 후 쓰기를 수행하는 정책이다.
- **쓰기 비할당(No-Write Allocate)**: 쓰기 실패 시 캐시에 적재하지 않고 하위 메모리에 직접 기록하는 정책이다.
- **쓰기 지역성(Write Locality)**: 동일한 영역에 짧은 시간 간격으로 쓰기 연산이 집중되는 참조 특성이다.
- **더티 비트(Dirty Bit)**: 캐시 라인의 내용이 하위 계층과 달라 최신 상태임을 나타내는 1비트 상태 플래그이다.
- **즉시 쓰기(Write-Through)**: 캐시 메모리 갱신과 동시에 하위 메모리에도 즉시 데이터를 기록하는 일관성 정책이다.
- **후기입(Write-Back)**: 캐시 메모리에만 먼저 쓰고 향후 라인이 축출될 때 하위 메모리에 반영하는 정책이다.
- **쓰기 병합(Write Combining)**: 동일 라인에 여러 번 쓰기가 일어나도 축출 시 단 1회만 전송하는 병합 효과이다.

</details>

- **쓰기 할당**과 **쓰기 비할당** 미스 처리 정책을 결합하여 가동함.
- **쓰기 지역성**이 높을수록 **후기입**과 **쓰기 병합** 효과를 발휘하여 버스 트래픽을 대폭 절감함.
- **후기입** 구조에서는 **더티 비트**를 관리하여 축출 시점에만 선택적으로 하위 계층을 덮어씀.

#### 한줄 요약

- 즉시 쓰기는 하위 계층을 즉시 동기화하고 후기입은 상태 비트를 활용한 병합 쓰기로 대역폭을 절감한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **캐시 배열(Cache Array)**: 태그와 데이터, 상태 플래그를 저장하는 고속 메모리 물리 배열이다.
- **쓰기 버퍼(Write Buffer)**: 주기억장치 쓰기 완료를 기다리지 않도록 요청을 임시 큐잉하는 버퍼이다.
- **버퍼 포화(Buffer Saturation)**: 연속적인 쓰기 요청이 버퍼 배출 속도를 초과하여 처리 대기에 빠지는 상태이다.
- **쓰기 정책 제어부(Write Policy Logic)**: 쓰기 명령 수신 시 적중 여부 및 정책 설정에 따라 데이터 경로를 선택하는 하드웨어 장치이다.

</details>

```text
[ 캐시 쓰기 정책 제어 구조 ]
 ├─ 즉시 쓰기 경로
 │  ├─ 캐시 배열 갱신
 │  ├─ 쓰기 버퍼 임시 저장
 │  └─ 하위 계층 전송
 └─ 후기입 경로
    ├─ 캐시 배열 갱신
    ├─ 더티 비트 설정
    └─ 축출 시 하위 계층 전송
```

| 구성요소 | 책임 |
|:---|:---|
| 쓰기 정책 제어부 | 적용된 쓰기 정책에 따른 경로 선택 및 제어 |
| 더티 비트 | **후기입** 캐시 라인의 하위 계층 미반영 상태 표시 |
| 쓰기 버퍼 | 하위 계층 쓰기 요청의 비동기 큐잉 |
| 하위 메모리 계층 | **즉시 쓰기** 요청과 축출 라인의 최종 저장 |

#### 한줄 요약

- 정책 제어부, 상태 비트, 쓰기 버퍼를 유기적으로 구동하여 하위 메모리로의 전송 지연을 은닉한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **더티 축출(Dirty Eviction)**: 새로운 라인을 적재하기 위해 기존 변경된 캐시 라인을 비우고 데이터를 하위 계층으로 밀어 넣는 작업이다.
- **캐시 플러시(Cache Flush)**: 장치 통신이나 전원 차단 전에 캐시 내의 모든 변경 데이터를 하위 계층으로 강제 반영하는 유지 관리 연산이다.

</details>

```text
[ 데이터 쓰기 연산 요청 ]
           │
           ▼
     [ 설정 정책 확인 ]
           │
     ┌─────┴─────┐
     ▼           ▼
[ 즉시 쓰기 ] [ 후기입 ]
     │           │
     ▼           ▼
[ 캐시 갱신 ] [ 캐시 갱신 ]
     │           │
     ▼           ▼
[ 버퍼 전송 ] [ 더티 설정 ]
     │           │
     ▼           ▼
[ 즉시 동기화] [ 축출 동기화 ]
```

### 동작 원리

1. 즉시 쓰기 동작: 캐시 갱신과 동시에 **쓰기 버퍼**로 요청을 전송하여 하위 계층을 즉시 동기화함.
2. 후기입 동작: 캐시에만 수정 사항을 반영하고 **더티 비트**를 갱신함.
3. 더티 축출: 새로운 데이터를 위해 교체할 기존 라인이 발생하면 **더티 축출**을 수행하여 하위 계층에 기록함.
4. 강제 동기화: 통신이나 종료 시 **캐시 플러시**를 수행하여 상태를 동기화함.

#### 한줄 요약

- 즉시 쓰기는 버퍼 기반 즉시 전송을 수행하고, 후기입은 상태 갱신 후 라인 교체 시점에 선택적 축출을 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **즉시 가시성(Immediate Visibility)**: 쓰기 즉시 하위 메모리나 주변 장치가 최신 데이터를 그대로 관측할 수 있는 성질이다.
- **더티 데이터(Dirty Data)**: 캐시에만 존재하고 메인 메모리에는 아직 반영되지 않은 일시적 불일치 최신 데이터이다.

</details>

| 비교 항목 | 즉시 쓰기 | 후기입 |
|:---|:---|:---|
| 메모리 동기화 시점 | 캐시 갱신 시 즉시 동기화 | 캐시 라인 축출 시 지연 동기화 |
| 메모리 버스 트래픽 | 매우 높음 | **쓰기 병합** 효과로 대폭 절감 |
| 하드웨어 구현 | **쓰기 버퍼**만 필요하여 단순함 | **더티 비트** 및 축출 로직이 필요하여 복잡함 |
| 데이터 일관성 | **즉시 가시성** 확보 | **더티 데이터** 존재로 불일치 구간 발생 |
| 주요 할당 정책 | 주로 **쓰기 비할당** 방식과 결합 | 주로 **쓰기 할당** 방식과 결합 |

#### 한줄 요약

- 즉시 쓰기는 즉각적인 가시성과 구현 단순성에 유리하며, 후기입은 쓰기 대역폭 절감 및 성능 최적화에 강점을 가진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비일관성 DMA(Non-Coherent DMA)**: 하드웨어 일관성 장치가 없는 환경에서 외부 장치가 메모리를 읽어 불일치가 발생하는 현상이다.
- **메모리 장벽(Memory Barrier)**: 대기 중인 메모리 연산이 완전히 전송될 때까지 후속 메모리 연산을 지연시키는 동기화 명령이다.
- **캐시 정리(Cache Clean)**: 외부 통신 전에 캐시 내의 더티 라인을 메인 메모리로 강제 기록하는 유지 관리 명령이다.
- **캐시 무효화(Cache Invalidate)**: 외부 수신 후 오래된 캐시 데이터를 파기하여 최신 수신값을 읽도록 유도하는 명령이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 즉시 쓰기의 연속 요청으로 인한 **버퍼 포화** 및 대기 발생 | **쓰기 버퍼** 용량 확장 및 시스템의 **후기입** 전환 적용 | 트래픽 병목 해소 및 프로세서 지연 방지 |
| 후기입 환경에서 예기치 않은 전원 손실로 **더티 데이터** 유실 | 플랫폼 지속성 도메인 확보 및 전원 종료 전 **캐시 플러시** | 완료된 쓰기의 영구적 보존 및 무결성 유지 |
| **비일관성 DMA** 장치가 최신 데이터를 관측하지 못하는 오류 | 송신 전 **캐시 정리**, 수신 직후 **캐시 무효화** 수행 | 프로세서와 외부 장치 간의 데이터 일관성 완벽 보장 |
| 다중 코어 환경에서 복잡한 쓰기 순서 교란 및 경합 발생 | **메모리 장벽** 명령어의 명시적 배치 및 동기화 | 코어 간 데이터 갱신 관측 순서 보장 |

#### 한줄 요약

- 버퍼 병목, 데이터 유실, 주변 장치 비일관성을 방어하기 위해 플러시 및 메모리 장벽 등 소프트웨어 제어를 병행한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **쓰기 정책 선택 기준(Write Policy Selection Criteria)**: 시스템의 대역폭 여유, 데이터 일관성 요구 사항, 전원 백업 능력 등을 종합 평가하여 최적의 아키텍처를 결정하는 체계이다.

</details>

- **쓰기 지역성**이 높으면 후기입을, 주변 장치 동기화 및 가시성이 우선이면 즉시 쓰기를 선택함

#### 한줄 요약

- 대역폭 절감 요구와 일관성 가시성을 종합적으로 측정하는 쓰기 정책 선택 기준에 따라 최적의 하드웨어 방식을 채택해야 한다.
