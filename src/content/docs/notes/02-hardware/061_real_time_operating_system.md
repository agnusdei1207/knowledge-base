## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 운영체제(Real-Time Operating System, RTOS)**: 논리적 연산 결과의 정확성뿐만 아니라 사전에 정의된 엄격한 마감시간(Deadline) 내에 제어 출력을 완료하도록 결정론적 선점 스케줄링을 보장하는 운영체제.
- **결정론적 응답성(Deterministic Responsiveness)**: 동일한 외부 입력 조건에서 이벤트 발생부터 처리 완료까지 소요되는 지연시간의 상한선(Worst-Case Execution Time, WCET)이 수학적으로 항상 일정하게 보장되는 특성.

</details>

- 정의/개념: 태스크별 엄격한 마감시간(Deadline) 준수를 위해 선점형 우선순위 스케줄러와 최소 인터럽트 지연을 제공하는 **실시간 운영체제(RTOS) 커널 아키텍처**
- 배경/필요성: 평균 처리량(Throughput)과 공정성(Fairness)을 중시하는 범용 OS(GPOS)의 가변 지연과 불확정성으로는 **자동차, 항공, 산업 로봇의 치명적 오작동 방지 불가**

#### 한줄 요약
- RTOS는 평균 처리 속도가 아닌 최악 응답 시간(WCRT)의 상한을 보장하여 시스템의 실시간 결정성을 확보하는 운영체제이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선점형 우선순위 스케줄링(Preemptive Priority Scheduling)**: 더 높은 우선순위 태스크가 Ready 상태가 되는 즉시 현재 실행 중인 저순위 태스크를 가로채고 CPU 제어권을 즉각 획득하는 메커니즘.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 인터럽트 지연, 문맥 교환, 락 블로킹을 모두 포함하여 태스크가 완료되기까지 소요될 수 있는 최대 지연시간.

</details>

- 결정론적 선점 스케줄링: **선점형 우선순위 스케줄러**를 기반으로 고순위 제어 태스크의 마이크로초 단위 즉시 실행 보장
- 마이크로커널 최소 지연: 커널 임계 구역(Critical Section)과 인터럽트 비활성화 구간을 극소화하여 **최악 응답 시간(WCRT)** 상한 사수
- 메모리 결정성 확보: 동적 힙 할당에 따른 단편화(Fragmentation)를 배제하고 고정 크기 **정적 메모리 풀(Memory Pool)** 운용

#### 한줄 요약
- 선점형 우선순위 스케줄링, 최소 인터럽트 지연, 정적 메모리 풀을 통해 시간적 결정론을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **태스크 제어 블록(Task Control Block, TCB)**: 태스크의 실행 상태(Ready/Running/Blocked), 스택 포인터(SP), 우선순위, 레지스터 문맥을 보관하는 커널 핵심 데이터 구조.
- **프로세스 간 통신(Inter-Process Communication, IPC)**: 큐(Queue), 세마포어(Semaphore), 뮤텍스(Mutex), 이벤트 플래그를 통해 태스크 간 동기화와 데이터 교환을 수행하는 메커니즘.

</details>

```text
[RTOS 마이크로커널 아키텍처]
 ┌─ [사용자 애플리케이션 계층] ──── 긴급 제어 태스크 / 주기적 통신 태스크 / 배경 태스크
 │
 ├─ [RTOS 마이크로커널 핵심 엔진]
 │   ├─ [선점형 스케줄러 (Preemptive Scheduler)] ── Ready 우선순위 큐 관리
 │   ├─ [문맥 교환 관리자 (Context Switcher)] ─── TCB 및 하드웨어 레지스터 저장/복원
 │   ├─ [동기화 및 IPC 모듈] ───────────────────── 뮤텍스 (PIP/PCP), 세마포어, 메시지 큐
 │   ├─ [소프트웨어 타이머 관리자] ────────────── 하드웨어 시스템 틱(SysTick) 기반 지연 제어
 │   └─ [정적 메모리 풀 관리자] ───────────────── O(1) 상수 시간 비단편화 블록 할당
 │
 └─ [하드웨어 추상화 및 인터럽트단] ── 하드웨어 타이머 (SysTick) + 인터럽트 컨트롤러 (NVIC)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어/커널 소속 및 포함 관계; SysTick 인터럽트가 발생하면 스케줄러가 TCB를 참조하여 최우선순위 태스크를 디스패치함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **선점형 스케줄러** | 커널 핵심 | 우선순위 큐에서 가장 높은 우선순위 태스크를 선택해 CPU 실행권 위임 | $O(1)$ 비트맵 스케줄링 |
| **TCB 관리자** | 커널 메모리 | 태스크별 독립 스택 포인터(SP), 레지스터 문맥 및 상태 전이 관리 | 문맥 보존 |
| **IPC 동기화 모듈** | 커널 서브시스템 | 세마포어, 큐 및 **우선순위 상속(PIP) 지원 뮤텍스** 제공 | 자원 상호배제 |
| **정적 메모리 풀** | 커널 메모리 | 런타임 단편화를 원천 배제하고 $O(1)$ 상수 시간 내 메모리 할당/해제 | 고정 블록 할당 |
| **SysTick 타이머** | 하드웨어-커널 경계 | 정밀 주기적 타임 슬라이스 및 태스크 타임아웃 틱 제공 | 1ms / 100us 인터럽트 |

#### 한줄 요약
- RTOS는 선점형 스케줄러, TCB 관리자, 동기화 IPC 모듈, 정적 메모리 풀 및 SysTick 타이머로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우선순위 상속(Priority Inheritance Protocol, PIP)**: 공유 자원을 획득한 저순위 태스크의 우선순위를 해당 자원을 기다리는 고순위 태스크 수준으로 임시 승격시키는 기법.

</details>

```text
1. 하드웨어 외부 인터럽트(ISR) 발생 ➔ 이벤트 감지 및 고순위 태스크 깨움(Unblock)
                      │
                      ▼
2. 스케줄러: 깨어난 태스크의 우선순위가 현재 실행 중인 태스크보다 높은가?
   ┌──────────────────┴──────────────────┐
[ 아니오 (우선순위 낮음) ]             [ 예 (고순위 태스크) ]
   │                                     │
   ▼                                     ▼
3. Ready 큐에 삽입 후 대기               3. 현재 태스크 레지스터 문맥을 TCB에 저장하고 즉각 선점(Preemption)
   │                                     │
   │                                     ▼
   │                                  4. 고순위 태스크가 필요한 공유 뮤텍스를 획득하였는가?
   │                                     ┌──────────┴──────────┐
   │                                   [ 즉시 획득 (경합 없음) ] [ 자원 선점 중 (경합 발생) ]
   │                                     │                     │
   │                                     ▼                     ▼
   │                                   5. 실시간 제어 연산     5. 자원을 쥔 저순위 태스크의
   │                                      마감시간 내 즉시 완수   우선순위를 고순위로 승격 (PIP)
   │                                     │                     │ ➔ 신속한 자원 해제 유도
   │                                     └─────────────────────┤
   │                                                           ▼
   │                                                        6. 제어 출력 후 문맥 복원 ➔ 이전 태스크 재개
   └───────────────────────────────────────────────────────────┘
```

분기 결과: **고순위 태스크가 깨어나면** 1클록 내에 선점되며, **자원 경합 시에는** PIP를 통해 블로킹 시간을 최소화함

#### 한줄 요약
- 인터럽트 ➔ 우선순위 비교 ➔ 즉각 선점 ➔ 자원 경합 시 PIP 적용 ➔ 제어 연산 완수 ➔ 문맥 복원의 흐름으로 동작한다.

## Ⅴ. 종류 및 비교

| 운영체제 유형 | RTOS (FreeRTOS, VxWorks, QNX) | 범용 OS (Linux, Windows) | 임베디드 Linux (PREEMPT_RT) |
|:---|:---|:---|:---|
| 최우선 설계 목표 | **결정론적 마감시간 준수 (Determinism)** | 처리량 극대화 및 공정성 (Throughput) | 범용 생태계 + 준 실시간성 |
| 스케줄링 알고리즘 | **엄격한 선점형 우선순위 (Priority-Based)** | 완전 공정 스케줄러 (CFS), 다단계 피드백 | 선점형 커널 패치 기반 우선순위 |
| 인터럽트 지연시간 | **수 마이크로초 ($\mu\text{s}$) 이하 보장** | 수 밀리초 ($\text{ms}$) 이상 가변적 | 수십 마이크로초 ($\mu\text{s}$) 수준 |
| 메모리 관리 방식 | **정적 메모리 풀, 가상 메모리 미사용/제한**| **MMU 기반 요구 페이징 및 가상 메모리**| MMU 가상 메모리 (Page Fault 지연) |
| 주요 적용 분야 | **차량 ECU, 항공 비행 제어, 의료 기기** | PC, 스마트폰, 클라우드 서버 | 산업용 게이트웨이, 로봇 제어기 |

#### 한줄 요약
- 마감시간 준수가 생명인 제어 시스템에는 RTOS가 필수이며, 복잡한 통신과 멀티미디어 처리에는 임베디드 리눅스가 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 각 뮤텍스에 접근 가능한 최고 태스크의 우선순위를 천장값으로 부여하여 연쇄 블로킹과 데드락을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 경합으로 인한 **우선순위 역전(Priority Inversion)** | **우선순위 상속(PIP) 및 우선순위 천장(PCP) 프로토콜 적용** | 고순위 태스크의 블로킹 시간 상한선 보장 |
| 잦은 문맥 교환으로 인한 CPU 인터럽트 오버헤드 | **ISR 작업 분리(Top-Half 즉각 처리 + Bottom-Half 태스크 위임)** | 인터럽트 마스킹 시간 최소화 |
| 태스크 스택 오버플로로 인한 메모리 오염 및 시스템 다운 | **하드웨어 MPU(Memory Protection Unit) 스택 영역 보호 설정** | 스택 침범 감지 시 즉각 예외 트랩 발생 |

#### 한줄 요약
- 실무에서는 PIP/PCP로 우선순위 역전을 잡고, ISR 분리로 지연을 줄이며, MPU로 스택 침범을 방어한다.

## Ⅶ. 결론

- 마감시간 위반이 치명적 인명·설비 사고로 직결되는 임베디드 제어 시스템을 위해 **결정론적 선점 스케줄링을 보장하는 RTOS(FreeRTOS/QNX)를 표준 도입**하고, 자원 경합을 통제하기 위해 **우선순위 상속(PIP) 및 천장(PCP) 프로토콜**을 적용하며, 시스템 신뢰성을 위해 **정적 메모리 풀과 MPU 스택 보호 체계**를 필수 구현하는 고신뢰 실시간 제어 아키텍처 확립

#### 한줄 요약
- RTOS는 선점형 스케줄링과 동기화 프로토콜을 통해 어떤 부하에서도 결정론적 응답성을 보장하는 실시간 제어의 두뇌이다.
