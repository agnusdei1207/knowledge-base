## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RTOS(Real-Time Operating System)**: 정해진 시간 제약(Deadline) 내에 논리적으로 정확한 연산 결과를 출력하도록 결정론적 스케줄링을 보장하는 운영체제.
- **결정론적 응답성(Deterministic Responsiveness)**: 동일한 조건에서 이벤트 발생 후 처리 완료까지 걸리는 시간의 상한선(WCET)이 항상 수학적으로 보장되는 특성.

</details>

- 정의/개념: 태스크별 마감시간 준수를 위해 선점형 우선순위 스케줄링과 최소 인터럽트 지연을 보장하는 **실시간 운영체제(RTOS)**
- 배경/필요성: 처리량과 공정성 중심의 범용 OS로는 **엄격한 실시간 마감시간 보장 불가**

#### 한줄 요약
- RTOS는 평균 처리 속도가 아닌 최악 응답 시간(WCRT)의 상한을 보장하여 시스템의 실시간 신뢰성을 확보한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선점형 우선순위 스케줄링(Preemptive Priority Scheduling)**: 더 높은 우선순위 태스크가 준비되면 현재 실행 중인 저순위 태스크를 즉시 중단시키고 CPU를 차지하는 방식.
- **최악 응답 시간(WCRT, Worst-Case Response Time)**: 인터럽트 지연, 문맥 교환, 락 블로킹 등을 모두 포함해 태스크 완료까지 걸릴 수 있는 최악의 시간.

</details>

- **선점형 우선순위 스케줄링** 기반 상위 태스크의 즉각적 CPU 실행권 확보
- 인터럽트 지연과 문맥 교환 시간이 상한을 갖도록 커널 임계구역 최소화
- **최악 응답 시간(WCRT)** 분석을 통한 수학적 스케줄러 적합성 증명 가능

#### 한줄 요약
- 고순위 태스크의 즉각 선점과 예측 가능한 지연 상한을 보장하는 것이 RTOS의 본질이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCB(Task Control Block)**: 태스크의 실행 상태(Ready/Blocked), 레지스터 스택 포인터, 우선순위 정보를 담고 있는 커널 제어 블록.
- **IPC(Inter-Process Communication)**: 태스크 간에 큐(Queue), 세마포어(Semaphore), 뮤텍스(Mutex), 이벤트 플래그로 데이터를 동기화하는 기법.

</details>

```text
[RTOS 커널 구조]
|-- 인터럽트·타이머 틱 계층 (하드웨어 이벤트 진입점)
|-- 마이크로커널 핵심 엔진
|   |-- 선점형 스케줄러 (우선순위 기반 Ready 큐 관리)
|   |-- 문맥 교환 및 TCB 관리자
|   |-- 동기화·IPC 모듈 (뮤텍스·세마포어·메시지 큐)
|   |-- 소프트웨어 타이머 및 지연 관리자
|   `-- 고정 크기 메모리 풀 관리자 (비단편화 메모리)
`-- 사용자 태스크 계층 (긴급 제어·통신 처리·배경 태스크)
```

선의 의미: 계층 및 커널 모듈 결합 구조

| 구성요소 | 책임 |
|:---|:---|
| 선점형 스케줄러 | Ready 큐에서 가장 높은 우선순위 태스크를 선택해 CPU 실행권 부여 |
| **TCB 관리자** | 실행 상태, 레지스터 스택 포인터, 우선순위 보관 및 문맥 전환 제어 |
| **IPC 모듈** | 큐, 세마포어, 뮤텍스를 통한 태스크 간 상호배제 및 데이터 동기화 |
| 타이머 관리자 | 주기적 하드웨어 틱(Tick) 기반 지연 시간 및 타임아웃 정밀 제어 |
| 메모리 풀 관리자 | 고정 크기 블록 할당으로 메모리 단편화 및 불확정 지연 원천 차단 |

#### 한줄 요약
- 스케줄러, TCB 관리자, 동기화 IPC, 메모리 풀 모듈이 마이크로커널 형태로 결합되어 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 전이(State Transition)**: 태스크가 Ready(준비), Running(실행), Blocked(대기/지연) 상태 간을 오가는 과정.

</details>

```text
외부 인터럽트 발생 → ISR이 이벤트 통지
        │
   깨어난 태스크가 현재 태스크보다 높은 우선순위인가?
   ┌────┴─────┐
아니오          예
   │             │
준비 큐에서     현재 태스크 문맥을 TCB에 저장 후 선점
대기 유지         │
   │        긴급 태스크가 필요한 공유 자원을 획득했는가?
   │        ┌────┴─────┐
   │        예          아니오 (뮤텍스 경합)
   │        │             │
   │     즉시 실행     자원 보유 태스크 우선순위 상속(PIP) 승격
   │        │             │
   │        └────┬────────┘
   │             │
   │        마감시간 내 제어 연산 완료
   └────┬────────┘
        │
   문맥 복원 후 이전 태스크 재개
```

#### 한줄 요약
- 인터럽트 발생 → 우선순위 비교 후 선점 → 공유 자원 접근 및 우선순위 상속 → 연산 완료 후 복귀 순으로 실행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **GPOS(General Purpose OS)**: Windows, Linux처럼 높은 처리율과 사용자 편의성을 목표로 하는 범용 운영체제.
- **베어메탈(Bare-Metal)**: OS 없이 하드웨어 레지스터를 직접 제어하는 메인 루프 기반 펌웨어.

</details>

| 운영체제 아키텍처 | RTOS (실시간 OS) | GPOS (범용 OS) | 베어메탈 (No OS) | 임베디드 리눅스 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 미션 크리티컬 차량·항공·의료 제어 | PC·스마트폰 멀티미디어·사무용 | 극소형 초저가 가전 센서 노드 | 스마트 게이트웨이·복잡한 통신 장비 |
| 핵심 특징 | 선점형 우선순위 스케줄링 및 결정론적 응답 | 공정성(Fairness) 기반 시분할 및 높은 처리율 | OS 없이 메인 무한 루프 직접 폴링 | 광범위한 드라이버 지원 및 오픈소스 |
| 한계 | 지원 라이브러리 및 복잡한 GUI 부재 | 비결정적 지연(지연시간 예측 불가) | 코드 복잡도 증가 시 유지보수 한계 | 실시간성 보장 불가(PREEMPT_RT 필요) |

#### 한줄 요약
- 마감시간 준수가 핵심인 제어 시스템에는 RTOS가, 풍부한 기능과 네트워크 처리가 필요한 장비에는 임베디드 리눅스가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 중간 순위 태스크가 실행되면서 자원을 쥐고 있는 저순위 태스크를 가로채 고순위 태스크가 무한정 대기하는 현상.
- **우선순위 상속(Priority Inheritance)**: 공유 자원을 획득한 저순위 태스크의 우선순위를 자원을 기다리는 고순위 태스크 수준으로 임시 승격시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 점유로 **우선순위 역전** 발생 | **우선순위 상속(PIP)** 및 우선순위 올림(PCP) 적용 | 고순위 태스크 블로킹 시간 상한선 보장 |
| 잦은 문맥 교환으로 인한 CPU 오버헤드 | ISR 작업 최소화(Top-half/Bottom-half 분리) | 인터럽트 지연 단축 및 실효 처리율 향상 |
| 태스크 스택 오버플로로 메모리 손상 | 스택 워터마크 감시 및 MPU 기반 메모리 보호 | 스택 침범 조기 탐지 및 안정성 확보 |
| 동적 메모리 할당으로 단편화 및 불확정 지연 | 고정 크기 메모리 블록 풀(Memory Pool) 운용 | O(1) 상수 시간 할당 및 단편화 원천 방지 |

#### 한줄 요약
- 우선순위 상속으로 락 역전을 방지하고, 고정 크기 메모리 풀과 MPU 스택 보호로 시스템 결정성을 확보한다.

## Ⅶ. 결론

- 마감시간 위반이 시스템 치명적 결함으로 이어지는 환경은 **선점형 RTOS 커널**을 채택하고, 최악 응답 시간(WCRT) 검증을 거쳐 확정적 실시간성 달성

#### 한줄 요약
- RTOS 도입의 핵심은 선점형 우선순위 스케줄링과 우선순위 상속 프로토콜을 통해 어떠한 부하 상황에서도 결정론적 응답성을 보장하는 데 있다.
