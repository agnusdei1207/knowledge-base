## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 운영체제(Real-Time Operating System, RTOS)**: 태스크의 시간 제약을 분석하고 마감시간 준수를 우선하는 운영체제.
- **결정론적 응답성(Deterministic Responsiveness)**: 실행·블로킹·간섭 시간을 분석해 응답 시간 상한을 예측할 수 있는 특성.

</details>

- 정의/개념: 태스크의 마감시간 준수를 우선하는 **실시간 운영체제(RTOS)**
- 배경/필요성: 범용 OS(GPOS)의 평균 처리량 중심 비선점 구간 및 페이징 지연으로 인한 **응답 시간 불확정성(Non-deterministic Jitter) 및 마감시간 초과 위험**

#### 한줄 요약
- RTOS는 평균 처리 속도가 아닌 최악 응답 시간(WCRT)의 상한을 보장하여 시스템의 실시간 결정성을 확보하는 운영체제이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선점형 우선순위 스케줄링(Preemptive Priority Scheduling)**: 더 높은 우선순위 태스크가 Ready 상태가 되는 즉시 현재 실행 중인 저순위 태스크를 가로채고 CPU 제어권을 즉각 획득하는 메커니즘.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 인터럽트 지연, 문맥 교환, 락 블로킹을 모두 포함하여 태스크가 완료되기까지 소요될 수 있는 최대 지연시간.

</details>

- 결정론적 스케줄링: 선점형 우선순위로 고순위 태스크의 대기 시간 상한 분석
- 커널 지연 통제: 임계 구역과 인터럽트 차단 시간을 줄여 **WCRT** 상한 관리
- 메모리 결정성: 정적 메모리 풀로 할당 지연과 단편화 변동 억제

#### 한줄 요약
- **선점형 우선순위 스케줄링**, 최소 인터럽트 지연, 정적 메모리 풀을 통해 시간적 결정론을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **태스크 제어 블록(Task Control Block, TCB)**: 태스크의 실행 상태(Ready/Running/Blocked), 스택 포인터(SP), 우선순위, 레지스터 문맥을 보관하는 커널 핵심 데이터 구조.
- **프로세스 간 통신(Inter-Process Communication, IPC)**: 큐(Queue), 세마포어(Semaphore), 뮤텍스(Mutex), 이벤트 플래그를 통해 태스크 간 동기화와 데이터 교환을 수행하는 메커니즘.
- **우선순위 상속(Priority Inheritance Protocol, PIP)**: 공유 자원을 획득한 저순위 태스크의 우선순위를 해당 자원을 기다리는 고순위 태스크 수준으로 임시 승격시키는 기법.

</details>

```text
+-------------------------------------------------------------------------------+
|                       RTOS 마이크로커널 아키텍처 및 계층 구조                 |
|                                                                               |
|  +-------------------------------------------------------------------------+  |
|  |     사용자 제어 애플리케이션 계층                                       |  |
|  |     [ 긴급 제어 태스크 ]    [ 주기적 통신 태스크 ]    [ 배경 로깅 태스크 ]|  |
|  +-------------------------------------------------------------------------+  |
|                                    │ 시스템 호출 API (OS Services)            |
|                                    ▼                                          |
|  +-------------------------------------------------------------------------+  |
|  |                     RTOS 마이크로커널 핵심 엔진                         |  |
|  |  +-----------------------------+     +-------------------------------+  |  |
|  |  | 선점형 우선순위 스케줄러    |     | 동기화 및 IPC 모듈            |  |  |
|  |  | - Ready 큐 관리 / O(1) 검색 |     | - 뮤텍스 (PIP/PCP 상속 프로토콜)|  |
|  |  +-----------------------------+     +-------------------------------+  |  |
|  |                 ▲                                    │                     |
|  |                 │ 스케줄링 트리거                    ▼                     |
|  |  +-----------------------------+     +-------------------------------+  |  |
|  |  | 문맥 교환기 (Context Switch)|     | 정적 메모리 풀 및 소프트웨어  |  |  |
|  |  | - TCB 저장/복원 (SP/레지스터) |     | - 고정 크기 블록 할당, SysTick|  |  |
|  |  +-----------------------------+     +-------------------------------+  |  |
|  +-------------------------------------------------------------------------+  |
|                                    │ HAL 추상화 계층                          |
|                                    ▼                                          |

|  |         하드웨어 계층: NVIC 인터럽트 컨트롤러 & SysTick 타이머           |  |

+-------------------------------------------------------------------------------+
```

- 신호 및 연결 관계: 하단 SysTick 주기 틱 또는 외부 하드웨어 인터럽트가 발생하면 커널 스케줄러가 TCB 문맥을 전환(`▲▼`)하여 O(1) 상수 시간 내에 최우선순위 태스크를 CPU로 디스패치함을 명시함

| 구성요소 | 책임 |
|:---|:---|
| 선점형 스케줄러 | 우선순위 큐에서 실행 태스크 선택 |
| TCB 관리자 | 태스크 상태·스택·레지스터 문맥 보관 |
| **IPC** 동기화 모듈 | 큐·세마포어·**우선순위 상속** 제공 |
| 정적 메모리 풀 | 고정 블록으로 할당 지연 변동 억제 |
| 시스템 타이머 | 주기 실행과 타임아웃 기준 제공 |

#### 한줄 요약
- 정적 메모리 풀이 요청마다 빈 공간을 찾아다니던 동적 할당을 고정 블록 배분으로 갈아치워 할당 시간의 상한을 확정하고, 시스템 타이머는 그 상한을 지켰는지 판정할 공통 시간 기준을 스케줄러에 공급한다.

## Ⅳ. 흐름도

```text
[외부 센서 이벤트 및 하드웨어 인터럽트 인입]
                     │
                     ▼
1. 인터럽트 컨트롤러(NVIC)의 최우선 하드웨어 ISR 즉각 분기
                     │
                     ▼
2. ISR의 대기 태스크 Ready 상태 전이 및 우선순위 비교
    ┌────────────────┴────────────────┐
 [ 현재 실행 태스크보다 낮음 ]       [ 현재 태스크보다 고순위 ]
    │                                 │
    ▼                                 ▼
Ready 큐에 정렬 대기 유지             3. 현재 태스크 문맥(TCB) 스택 저장 및 선점(Preemption) 단행
    │                                 │
    │                                 ▼
    │                              4. 공유 자원(뮤텍스) 점유 상태 검증
    │                                 ┌───────┴───────┐
    │                              [ 즉시 획득 ]   [ 저순위 태스크 점유 중 ]
    │                                 │               │
    │                                 ▼               ▼
    │                              즉시 제어 연산   우선순위 상속(PIP) 발동 ➔ 신속 해제 유도
    │                                 │               │
    │                                 └───────┬───────┘
    │                                         │
    ▼                                         ▼
5. 제어 출력 완수 및 차순위 태스크 문맥 복원(Context Restore)
```

- 분기 결과: 고순위 태스크 도착 시 저순위 태스크를 즉각 선점하며, 뮤텍스 충돌 시 우선순위 상속(PIP)을 발동하여 우선순위 역전 지연을 차단함

**동작 원리**

1. 센서 트리거가 발생하면 CPU 하드웨어가 NVIC 인터럽트 벡터 테이블을 참조하여 즉시 ISR(Interrupt Service Routine)로 제어권을 넘긴다.
2. ISR이 세마포어를 해제하여 대기 중이던 실시간 제어 태스크를 Ready 큐로 이동시키고, 커널 스케줄러에 스케줄링 플래그를 설정한다.
3. 스케줄러가 Ready 큐의 헤드를 검사하여 깨어난 태스크가 현재 실행 중인 태스크보다 우선순위가 높음을 확인하면 즉각 문맥 교환을 개시하여 기존 레지스터를 TCB에 백업한다.
4. 실행 상태가 된 고순위 태스크가 공유 자원 접근을 시도할 때 저순위 태스크가 락을 쥐고 있으면 PIP 프로토콜에 의해 저순위 태스크의 우선순위를 일시 승격시켜 자원 해제를 가속한다.
5. 마감시간 내에 제어 연산과 물리 출력이 완수되면 태스크는 슬립 상태로 전이하고, 스케줄러는 백업된 TCB를 복원하여 원래 태스크로 복귀한다.

#### 한줄 요약
- 선점은 응답성을 사기 위해 이벤트마다 문맥 전환 비용을 지불하는 선택이므로, 우선순위 설계가 어긋나면 PIP로 되막아야 할 역전 구간을 스케줄러가 스스로 만들어 낸다.

## Ⅴ. 종류 및 비교

| 운영체제 유형 | RTOS (FreeRTOS, VxWorks, QNX) | 범용 OS (Linux, Windows) | 임베디드 Linux (PREEMPT_RT) |
|:---|:---|:---|:---|
| 적용 기준 | 초 단위 이하 결정론적 마감시간 엄격 준수 요구 시 | 다양한 응용 호환성 및 대규모 처리량 극대화 요구 시 | 리눅스 네트워크/미디어 스택을 활용하며 준실시간 제어 요구 시 |
| 최우선 설계 목표 | 결정론적 마감시간 준수 | 처리량 극대화 및 공정성 | 범용 생태계 및 준 실시간성 |
| 스케줄링 알고리즘 | 선점형 우선순위 스케줄링 | 완전 공정 스케줄러(CFS), 다단계 피드백 | 선점형 커널 패치 기반 우선순위 |
| 인터럽트 지연시간 | 분석 가능한 지연 상한 우선 | 처리량에 따른 지연 변동 | 선점 패치로 지연 변동 완화 |
| 메모리 관리 방식 | 정적 할당·잠금 메모리 우선 | MMU 기반 요구 페이징 | MMU와 페이지 폴트 통제 |
| 주요 적용 분야 | 차량 ECU, 항공 비행 제어, 의료 기기 | PC, 스마트폰, 클라우드 서버 | 산업용 게이트웨이, 로봇 제어기 |

#### 한줄 요약
- 마감시간 준수가 생명인 제어 시스템에는 RTOS가 필수이며, 복잡한 통신과 멀티미디어 처리에는 임베디드 리눅스가 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 각 뮤텍스에 접근 가능한 최고 태스크의 우선순위를 천장값으로 부여하여 연쇄 블로킹과 데드락을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 경합에 따른 우선순위 역전 | **우선순위 상속(PIP)** 및 **우선순위 천장(PCP)** 적용 | 고순위 태스크의 블로킹 시간 상한선 보장 |
| 잦은 문맥 교환으로 인한 인터럽트 오버헤드 | **ISR 상·하반부 분리(Top/Bottom-Half)** 기법 적용 | 인터럽트 마스킹 시간 최소화 |
| 태스크 스택 오버플로로 인한 메모리 오염 | **하드웨어 MPU** 스택 보호 영역 설정 | 스택 침범 감지 시 즉각 예외 트랩 발생 |

#### 한줄 요약
- 실무에서는 PIP/PCP로 우선순위 역전을 잡고, ISR 분리로 지연을 줄이며, MPU로 스택 침범을 방어한다.

## Ⅶ. 결론

- 하드 실시간(Hard Real-Time) 제어 분야의 결정론적 응답성 보장 표준 플랫폼(FreeRTOS, VxWorks, QNX 등)으로 독보적 위치를 점하고 있으며, 최근에는 PREEMPT_RT 패치가 리눅스 메인라인 커널에 공식 통합됨에 따라 이종 멀티코어 환경에서 하이퍼바이저 기반으로 RTOS와 범용 OS(GPOS)를 동시 가상화하는 융합 아키텍처로 진화하고 있으므로 엔지니어는 WCRT(최악 응답 시간) 분석과 우선순위 역전 방지 대책을 설계 초기부터 철저히 검증해야 한다.

#### 한줄 요약
- RTOS는 선점형 스케줄링과 동기화 프로토콜을 통해 어떤 부하에서도 결정론적 응답성을 보장하는 실시간 제어의 두뇌이다.
