## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RTOS(Real-Time Operating System)**: 태스크의 실행 시간과 마감시간(Deadline)을 수학적으로 예측하고 보장하는 결정론적(Deterministic) 커널.
- **Task(태스크)**: RTOS에 의해 독립적으로 스케줄링되는 최소 실행 단위로 고유의 우선순위, 스택, TCB를 보유.
- **Deadline(마감시간)**: 특정 이벤트 발생 후 태스크가 실행을 완료해야 하는 엄격한 시간적 제한선.

</details>

- 정의/개념: 외부 이벤트에 대해 지정된 마감시간(Deadline) 내에 결정론적(Deterministic)으로 연산 결과를 반환하도록 우선순위 선점 스케줄링 및 초저지연 인터럽트 처리를 지원하는 전용 운영체제
- 배경/필요성: 범용 OS(GPOS)의 비결정론적 스케줄링 지연(Throughput 지향)을 극복하고, **자동차 전장, 항공 우주, 산업 자동화 제어에서 미션 크리티컬 실시간성 및 안전성 보장**

#### 한줄 요약

- 우선순위 기반 선점 스케줄링으로 **결정론적 응답시간 및 실시간 마감시간(Deadline) 보장**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Determinism(시간 결정성)**: 시스템 부하나 외부 조건과 무관하게 인터럽트 지연과 문맥 전환 시간이 일정 상한(Upper Bound) 내로 고정되는 특성.
- **WCRT(Worst-Case Response Time)**: 인터럽트 지연, 우선순위 블로킹, 상위 태스크 간섭 시간을 모두 합산한 최악의 응답 시간.
- **Preemptive Priority Scheduling**: 고우선순위 태스크가 준비 상태가 되면 현재 실행 중인 저우선순위 태스크를 즉시 중단시키고 CPU를 선점하는 방식.

</details>

- 처리량(Throughput)보다 최악의 지연시간을 상한 내로 제한하는 **시간 결정성(Determinism) 보장**
- 긴급한 제어 태스크 발생 시 즉시 CPU 제어권을 넘겨받는 **우선순위 기반 선점형 스케줄링(Preemptive Scheduling)**
- 수학적 응답시간 분석(RTA)을 통해 마감시간 만족을 입증하는 **최악 응답 시간(WCRT) 검증 체계**

$$
R_i^{(k+1)} =
C_i + B_i +
\sum_{j \in hp(i)}
\left\lceil \frac{R_i^{(k)}}{T_j} \right\rceil C_j
$$

#### 한줄 요약

- **시간 결정성(Determinism)·우선순위 선점(Preemption)·WCRT 수학적 검증**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCB(Task Control Block)**: 태스크의 우선순위, 프로그램 카운터(PC), 스택 포인터(SP), 레지스터 상태를 저장하는 커널 자료구조.
- **Ready Queue**: 실행 가능한 상태의 태스크들을 우선순위 순서대로 정렬하여 보관하는 큐.
- **Priority Ceiling Protocol(PCP)**: 뮤텍스 획득 시 공유 자원의 상한 우선순위를 부여하여 우선순위 역전 및 데드락을 방지하는 동기화 기법.

</details>

```text
[ RTOS 커널 아키텍처 및 태스크 관리 구조도 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 인터럽트 관리 : 하드웨어 ISR (Top-Half) ──> DPC/Bottom-Half│
└──────────────────────────────┬──────────────────────────────┘
                               │ (이벤트 트리거)
┌──────────────────────────────┴──────────────────────────────┐
│ 2. RTOS 선점형 스케줄러 (Preemptive Priority Scheduler)    │
│  ├─ Ready Queue (우선순위 정렬 대기열)                       │
│  └─ TCB 관리 (Task Control Block & 문맥 보존/복원)           │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ CPU 디스패치 ]
┌──────────────────────────────┴──────────────────────────────┐
│ 3. 실시간 태스크 풀 (Task 0 : 긴급 제어, Task N : 배경 로깅)│
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 4. 동기화 및 IPC : Mutex (PIP/PCP 적용), Semaphore, Mailbox │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 인터럽트 서비스 루틴(ISR), 태스크 제어 블록(TCB) 및 준비 큐, 실시간 선점 스케줄러, 동기화/IPC(뮤텍스) 간의 RTOS 커널 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 관리 | 하드웨어 센서에 불이 들어오면 모든 걸 제쳐두고 가장 먼저 튀어 나가 처리하는 0순위 특수부대(**인터럽트 서비스 루틴**) |
| 태스크 제어 블록 및 큐 | 누가 대기 중인지 줄을 세우는 **준비 큐**와, 그놈의 현재 상태를 적어놓은 호적등본(**태스크 제어 블록**) |
| 실시간 스케줄러 | 대기 줄을 무시하고 VIP(고우선순위)가 오면 기존 놈을 걷어차고 CPU를 빼앗아버리는 권력자 |
| 동기화 관리 | 두 태스크가 하나의 램(RAM)을 동시에 물고 뜯지 않게 질서를 잡아주는 신호등(뮤텍스/세마포어) |

#### 한줄 요약

- **인터럽트 관리(ISR)·TCB 및 Ready Queue·우선순위 선점 스케줄러·동기화/IPC(Mutex)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Context Switch(문맥 전환)**: 실행 중인 태스크의 CPU 레지스터를 TCB에 저장하고 다음 실행할 태스크의 레지스터를 복원하는 과정.

</details>

```text
[ RTOS 태스크 상태 전이 및 선점 스케줄링 시퀀스 ]
                         ┌────────────────────────────────────────┐
                         │ [ 3. 고우선순위 태스크 등장 (선점 Preemption) ]│
                         │                                        │
                         ▼                                        │
[ Blocked (대기/차단) ] ── 1. 센서 이벤트 트리거 ──> [ Ready (준비 큐) ]   │
       ▲                                                 │        │
       │                                                 │        │
       │                                     2. 최고 우선순위 TCB 디스패치
       │                                     (초고속 문맥 전환 Context Switch)
       │                                                 │        │
       │                                                 ▼        │
       └── 4. Mutex/I/O 자원 대기 ──────────────── [ Running (실행) ] ───┘
                                                         │
                                                 5. 태스크 연산 완료
                                                         │
                                                         ▼
                                                 [ Terminated (종료) ]
```

**동작 원리**

1. **이벤트 트리거**: 센서 인터럽트 또는 타이머 만료 시 대기(Blocked) 태스크가 준비(Ready) 큐로 전이
2. **최우선 디스패치**: 스케줄러가 준비 큐에서 가장 우선순위가 높은 태스크를 선택하여 문맥 전환
3. **선점(Preemption)**: 실행 중인 저우선순위 태스크보다 높은 우선순위 태스크 도착 시 즉시 중단 및 교체
4. **자원 차단(Blocked)**: 실행 중 공유 자원(Mutex) 경합 발생 시 자원 해제 전까지 Blocked 상태로 유배
5. **완료 및 반환**: 마감시간 내에 연산을 마치고 CPU 자원을 반환하여 차순위 태스크 실행 허용

#### 한줄 요약

- 이벤트 발생 $\to$ **Ready 상태 진입 $\to$ 최고 우선순위 태스크 문맥 전환 $\to$ 실행 $\to$ 자원 경합 시 Blocked / 완료 시 Terminated**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RTOS vs Bare-Metal vs GPOS**:
  - RTOS: 우선순위 선점, 시간 결정성 보장, 수 $\mu\text{s}$ 지연 (전장/항공)
  - Bare-Metal: OS 없음, 폴링 루프, 단순 가전/초저비용
  - GPOS: 공평 시분할, 처리량 극대화, 비결정론적 지연 (스마트폰/PC)

</details>

| 비교 항목 | 실시간 운영체제 (RTOS) | 베어메탈 (Bare-Metal 무한 루프) | 범용 운영체제 (GPOS : Linux/Windows) |
|:---|:---|:---|:---|
| 스케줄링 및 지연 | 우선순위 기반 선점형 (결정론적 수 $\mu\text{s}$) | 폴링 기반 무한 루프 (인터럽트 지연 종속) | 공평 시분할(CFS) 비선점 혼합 (비결정론적 ms) |
| 메모리 및 코드 크기 | 소용량 풋프린트 (수십 KB Flash/RAM) | 극소 풋프린트 (수 KB, OS 오버헤드 0) | 대용량 메모리 필요 (수백 MB~GB 단위) |
| 한계 및 적합 분야 | 복잡한 UI/네트워크 처리 시 개발 난도 (전장 제어) | 코드 확장 시 스파게티화 (소형 가전) | 실시간 마감시간 보장 불가 (스마트폰/서버) |

#### 한줄 요약

- 하드 실시간은 **RTOS**, 초단순 제어는 **베어메탈**, 복합 멀티태스킹은 **GPOS**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Priority Inversion(우선순위 역전)**: 저우선순위 태스크가 획득한 뮤텍스를 기다리느라 고우선순위 태스크가 중우선순위 태스크보다 늦게 실행되는 현상.
- **Priority Inheritance Protocol(PIP)**: 뮤텍스를 보유한 저우선순위 태스크에게 대기 중인 고우선순위 태스크의 우선순위를 임시 상속하여 자원 해제를 가속하는 기법.
- **Stack Watermarking**: 스택 영역을 특정 매직 패턴(0xDEADBEEF)으로 채운 후 런타임에 잔여 패턴을 검사하여 스택 오버플로우를 감시하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하급자가 메모리를 물고 안 놔줘서 상급자가 일을 못 하고 대기 타는 하극상 대참사(**우선순위 역전**) 발발 | 하급자에게 잠시 상급자 계급장을 빌려줘서 빨리 일을 끝내고 메모리를 뱉게 만듦(**우선순위 상속**) | 엉뚱한 대기로 인해 최악 응답 시간(WCRT)이 뻥튀기되어 마감시간을 놓치는 대사태 완벽 차단 |
| 스케줄러가 너무 자주 태스크를 걷어차고 뇌 이식(문맥 전환) 하느라 실제 일은 못 하고 낭비되는 오버헤드 | 자질구레한 태스크를 하나로 합치고 급하지 않은 일은 나중에 처리하도록 지연 처리(Deferred Processing) 스케줄링 강제 | 스케줄러 뻘짓을 줄여 칩셋의 실제 퓨어 연산 CPU 활용률을 극한으로 쥐어짜는 최적화 달성 |
| 태스크가 지한테 할당된 램 선을 넘어 남의 구역까지 덮어써 버려 커널을 박살 내는 오버플로우 폭파 | 메모리 끝자락에 가비지 패턴을 채워 넣고 침범했는지 감시하는 깐깐한 **스택 워터마크** 모니터링 수용 | 메모리 오염으로 시스템이 원인도 모르게 뻗어버리는 끔찍한 셧다운 미스터리 원천 봉쇄 |

#### 한줄 요약

- **Priority Inheritance/Ceiling 프로토콜·지연 인터럽트(Bottom-Half) 처리·Stack Watermark 모니터링**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **기능 안전(Functional Safety) 국제 표준**: 자동차 ISO 26262(ASIL-D), 산업용 IEC 61508(SIL-3), 항공 DO-178C(DAL-A) 인증을 만족하는 신뢰성 검증된 RTOS 커널 필수.

</details>

- 미션 크리티컬 자동차(ISO 26262 ASIL-D), 항공(DO-178C) 및 제어 시스템에서 **AUTOSAR OS / FreeRTOS / QNX 기반 RTOS 표준 채택**

#### 한줄 요약

- **마감시간 엄수(Hard/Soft Real-Time)와 결정론적 WCRT 분석**에 기반한 RTOS 선정
