## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RTOS(Real-Time Operating System)**: 태스크 응답시간을 예측하고 마감시간 준수를 분석할 수 있게 하는 실시간 커널
- **태스크(Task)**: 커널 스케줄러에 의해 우선순위 및 상태가 관리되는 독립 실행 단위
- **데드라인(Deadline)**: 이벤트 발생 후 제어 출력이 반드시 완결되어야 하는 시간적 한계

- **실시간 운영체제(Real-Time Operating System, RTOS)**: 태스크 실행의 정확성뿐만 아니라 정해진 마감시간(Deadline) 내에 결과를 반환하는 결정론적(Deterministic) 시간 보장성을 핵심으로 하는 운영체제.
</details>

- 정의/개념: 우선순위 스케줄링과 지연 상한 분석을 지원하는 **RTOS**
- 배경/필요성: 범용 OS(GPOS)의 시분할(Time-sharing) 비결정성 및 베어메탈(Super-loop) 환경의 다중 태스크 복잡도 증가 한계 극복

#### 한줄 요약

- RTOS는 우선순위 선점과 예측 가능한 커널 서비스를 제공하며, 시스템 설계자는 WCET·차단·상위 태스크 간섭을 분석해 데드라인 충족을 입증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **결정성(Determinism)**: 최악 응답 지연의 상한을 예측할 수 있는 특성
- **WCET(Worst-Case Execution Time)**: 태스크 순수 연산의 최대 이론적 실행 시간
- **WCRT(Worst-Case Response Time)**: 이벤트 발생부터 완료까지의 최대 반응 시간
- **우선순위 선점(Priority-Based Preemption)**: 고우선순위 태스크 발생 시 저우선순위 태스크를 즉각 중단하는 스케줄링

</details>

- 평균 처리량보다 최악 실행시간인 **WCET/WCRT** 및 **결정성**을 우선 보장
- 긴급 태스크의 응답 지연을 줄이는 **우선순위 선점** 기반 스케줄링
- 인터럽트 지연시간 및 자원 선점 차단 시간을 포함한 **WCRT** 상한 입증

$$
R_i^{(k+1)} =
C_i + B_i +
\sum_{j \in hp(i)}
\left\lceil \frac{R_i^{(k)}}{T_j} \right\rceil C_j
$$

#### 한줄 요약

- 평균 처리량보다 **WCRT** 상한을 우선하는 결정성이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ISR(Interrupt Service Routine)**: 외부 하드웨어 인터럽트 수용 시 최우선 실행되는 커널 이벤트 루틴.
- **TCB(Task Control Block)**: 태스크 식별자, 우선순위, 스택 포인터, 레지스터 맥락(Context) 정보를 격리 저장하는 자료구조.
- **준비 큐(Ready Queue)**: 실행 가능한 태스크들을 우선순위에 따라 정렬하여 유지하는 대기열.
- **동기화 관리(Synchronization Management)**: 뮤텍스, 세마포어, 큐로 태스크 간 상호 배타적 자원 접근을 제어하는 모듈.

</details>

```text
[인터럽트 관리] -- [준비 큐•TCB] -- [스케줄러] -- [동기화 관리]
```

선의 의미: 인터럽트 관리가 이벤트를 받아 준비 큐/TCB를 갱신하고 스케줄러 및 동기화 관리 모듈이 자원을 할당하는 커널 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 관리 | 하드웨어 이벤트 빠른 수용 및 **ISR** 최우선 디스패치 |
| 준비 큐•TCB | 태스크 레지스터 Context, 우선순위 및 상태(**TCB**) 보관 |
| 스케줄러 | **우선순위 선점** 및 최우선 준비 태스크 코어 할당 |
| 동기화 관리 | 세마포어/뮤텍스 기반 공유 자원 배타적 보호 및 IPC 수용 |

#### 한줄 요약

- 인터럽트 관리가 이벤트를 준비 큐에 반영하고, 스케줄러가 TCB 우선순위와 동기화 상태로 실행·선점을 결정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **준비 상태(Ready State)**: 실행 준비가 완결되어 스케줄러의 코어 할당을 대기 중인 상태.
- **문맥 전환(Context Switch)**: 현 태스크 레지스터를 TCB에 저장하고 새 태스크 TCB 레지스터를 레지스터로 복원하는 커널 전환 작업.
- **차단 상태(Blocked State)**: 자원(Mutex) 반납이나 타이머 이벤트 대기를 위해 연산 자원을 내려놓은 상태.

</details>

```text
                         ┌──────────────────────┐
                         │ 3. 우선순위 선점    │
                         │                      │
                         ▼                      │
[차단 상태] ── 1. 이벤트 준비 ──► [준비 상태] │
      ▲                              │          │
      │                              │          │
      │                       2. 실행 태스크 선택
      │                              │          │
      │                              ▼          │
      └── 4. 대기 전환 ───────── [실행 상태] ──┘
                                     │
                              5. 실행 완료
                                     │
                                     ▼
                                 [종료 상태]
```

### 동작 원리

1. **이벤트 준비**: **ISR** 또는 타이머 만료를 통한 대기 태스크의 **차단 상태**->**준비 상태** 전환.
2. **실행 태스크 선택**: **준비 큐** 내 최고 우선순위 TCB 선택 및 **문맥 전환**을 통한 레지스터 복원.
3. **우선순위 선점**: 실행 도중 더 높은 우선순위 태스크 발생 시 기존 태스크를 **우선순위 선점**하여 준비 상태 축출.
4. **대기 전환**: 뮤텍스 획득 실패 시 태스크를 **차단 상태**로 이동.
5. **실행 완료**: 연산 종료 시 TCB 자원 해제 및 **종료 상태** 이전.

#### 한줄 요약

- RTOS 스케줄러는 준비·실행·차단 상태를 전환하고, 더 높은 우선순위 태스크가 준비되면 현재 태스크를 선점한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Bare Metal**: OS 없이 Infinite Loop(Super-loop) 상에서 하드웨어 인터럽트로 전 처리하는 구조.
- **GPOS(General-Purpose OS)**: Linux/Windows 등 평균 처리량 및 공정한 스케줄링을 최우선하는 범용 OS.

</details>

| 실행 환경 | RTOS (Real-Time OS) | Bare Metal (Super-loop) | GPOS (General-Purpose OS) |
|:---|:---|:---|:---|
| 적용 기준 | 엄격한 실시간 마감시간 준수 필요 시 | 소형 MCU 기반 저비용 단순 제어 시 | UI, 대용량 스토리지, 복잡 애플리케이션 시 |
| 핵심 특징 | **RTOS**의 선점형 스케줄링과 지연 상한 분석 | **Bare Metal**의 직접 하드웨어 접근과 단순성 | **GPOS**의 시분할 공정 스케줄링과 풍부한 API |
| 한계 | 메모리 풋프린트 오버헤드 | 시스템 복잡도 증가 시 커널 관리 불가 | **결정성** 부재 및 가변 지연 발생 |

#### 한줄 요약

- 다중 태스크의 데드라인 분석에는 RTOS, 최소 자원의 단순 제어에는 베어메탈, 풍부한 서비스와 평균 처리량에는 범용 운영체제가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 높은 우선순위 태스크가 낮은 태스크의 뮤텍스 점유로 인해 대기하는 동안 중간 우선순위 태스크가 먼저 실행되는 현상.
- **우선순위 상속(Priority Inheritance)**: 뮤텍스를 보유한 낮은 우선순위 태스크의 우선순위를 대기 중인 높은 태스크 레벨로 일시 상향하는 대책.
- **스택 워터마크(Stack Watermark)**: 태스크 스택 메모리 오버플로우를 감시하기 위해 특정 가비지 패턴을 채워 소비량을 계측하는 검사.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 뮤텍스 락으로 인한 **우선순위 역전** 발생 | **우선순위 상속** 또는 Priority Ceiling 프로토콜 적용 | 높은 우선순위 태스크 차단 시간 상한 보장 |
| 잦은 **문맥 전환**에 의한 커널 overhead 증대 | 태스크 통합 및 ISR 지연 처리(Deferred Processing) | CPU 연산 유효 활용률 향상 |
| 태스크 스택 메모리 오버플로우 위험 | **스택 워터마크** 모니터링 및 MPU/MMU 메모리 보호 | 메모리 오염 및 커널 락업 차단 |

> 사례: **우선순위 상속** 적용 전후의 차단 시간을 WCRT에 반영

#### 한줄 요약

- WCET, 공유 자원 차단과 상위 우선순위 간섭을 포함한 WCRT가 각 태스크의 데드라인 이하인지 검증한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스케줄 가능성(Schedulability)**: 모든 태스크의 WCRT가 데드라인 이하임을 증명하는 성질
- **OS 선정(OS Selection)**: 마감시간 임계성 및 풋프린트 기반 OS 선정 체계

</details>

- **OS 선정**에 따라 실시간 보장이 필수적인 전장·항공·산업용 시스템에 **RTOS** 채택

#### 한줄 요약

- 데드라인 분석은 RTOS, 단순 제어는 Bare Metal, 범용 서비스는 GPOS를 선택한다.
