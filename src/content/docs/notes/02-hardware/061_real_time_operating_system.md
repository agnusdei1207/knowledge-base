## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **실시간 운영체제(Real-time Operating System, RTOS)**: 태스크의 응답시간이 정해진 데드라인 안에 들도록 결정적 스케줄링을 제공하는 운영체제이다.
- **태스크(Task)**: RTOS 스케줄러가 상태와 우선순위를 가진 독립 실행 단위로 관리하는 작업이다.
- **데드라인(Deadline)**: 태스크의 요청이 발생한 뒤 실행 결과를 반드시 완료해야 하는 시각이다.

</details>

- 정의/개념: 우선순위 기반 태스크·인터럽트·동기화의 지연 상한을 분석할 수 있게 하는 **RTOS**이다.
- 배경/필요성: 슈퍼루프는 작업과 공유 자원이 늘수록 실행 간섭과 차단 조건이 결합되어 다중 태스크의 응답시간 입증이 복잡해진다.

#### 한줄 요약

- RTOS는 우선순위 선점과 예측 가능한 커널 서비스를 제공하며, 시스템 설계자는 WCET·차단·상위 태스크 간섭을 분석해 데드라인 충족을 입증한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **결정성(Determinism)**: 지정 조건에서 처리 지연의 최악 상한을 예측하고 재현할 수 있는 성질이다.
- **최악 실행시간(Worst-case Execution Time, WCET)**: 대기와 선점을 제외하고 태스크가 프로세서에서 실제 실행되는 최대 시간이다.
- **최악 응답시간(Worst-case Response Time, WCRT)**: 태스크 요청부터 차단과 간섭을 거쳐 처리 완료까지 걸리는 최대 시간이다.
- **우선순위 선점(Priority Preemption)**: 더 높은 우선순위 태스크가 준비되면 현재 태스크의 실행권을 가져오는 동작이다.

</details>

- 평균 처리량보다 **결정성**과 **WCET·WCRT** 예측을 우선한다.
- **우선순위 선점**으로 긴급 태스크의 응답시간을 줄인다.
- 인터럽트와 차단 시간이 늘면 **WCRT**가 증가한다.

$$
R_i^{(k+1)} =
C_i + B_i +
\sum_{j \in hp(i)}
\left\lceil \frac{R_i^{(k)}}{T_j} \right\rceil C_j
$$

> 고정 우선순위 주기 태스크를 가정하고 (R_i^{(0)}=C_i+B_i)에서 반복하며, 수렴한 WCRT가 데드라인 이하여야 스케줄 가능

#### 한줄 요약

- 평균 처리량보다 **WCRT** 상한을 우선하는 결정성이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 인터럽트 사건을 처리하는 루틴이다.
- **인터럽트 관리(Interrupt Management)**: ISR을 실행하고 관련 태스크를 준비 상태로 전환하는 기능이다.
- **태스크 제어 블록(Task Control Block, TCB)**: 태스크의 실행 상태와 우선순위, 레지스터 문맥 및 스택 정보를 저장하는 자료구조이다.
- **준비 큐(Ready Queue)**: 실행할 수 있는 태스크를 우선순위나 스케줄링 정책 순서로 보관하는 대기열이다.
- **동기화 관리(Synchronization Management)**: 여러 태스크의 실행 순서와 공유 자원 접근을 락이나 이벤트로 제어하는 기능이다.

</details>

```text
[인터럽트 관리] -- [준비 큐•TCB] -- [스케줄러] -- [동기화 관리]
```

선의 의미: 이벤트 관리, 태스크 상태 저장, 실행 결정, 공유 자원 보호 기능이 결합된 정적 RTOS 커널 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 관리 | 이벤트•시간 처리 |
| 준비 큐•TCB | 태스크 상태 보관 |
| 스케줄러 | 실행•선점 결정 |
| 동기화 관리 | 공유 자원 보호 |

#### 한줄 요약

- 인터럽트 관리가 이벤트를 준비 큐에 반영하고, 스케줄러가 TCB 우선순위와 동기화 상태로 실행·선점을 결정한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **준비 상태(Ready State)**: 필요한 이벤트를 받아 실행 가능하지만 아직 프로세서를 할당받지 못한 태스크 상태이다.
- **문맥 전환(Context Switch)**: 현재 태스크의 레지스터와 스택 상태를 저장하고 다음 태스크 상태를 복원하는 동작이다.
- **차단 상태(Blocked State)**: 태스크가 잠금이나 입출력 또는 이벤트를 기다리며 실행 후보에서 빠진 상태이다.
- **이벤트 준비**: 조건을 충족한 태스크를 차단 상태에서 준비 큐로 옮기는 단계이다.
- **실행 태스크 선택**: 가장 높은 우선순위의 준비 태스크를 고르고 문맥을 복원하는 단계이다.
- **우선순위 선점**: 더 높은 우선순위 태스크가 준비되면 현재 태스크의 실행권을 넘기는 단계이다.
- **대기 전환**: 실행 태스크가 자원이나 이벤트를 기다리면 차단 상태로 옮기는 단계이다.
- **실행 완료**: 태스크 종료와 자원 해제를 기록하고 후속 태스크를 준비시키는 단계이다.

</details>

```text
                         ┌──────────────────────┐
                         │ 3. 우선순위 선점    │
                         │                      │
                         ▼                      │
[차단 상태] ── 1. 이벤트 준비 ──► [준비 상태] │
      ▲                              │          │
      │                              │          │
      │                       2. 실행 태스크 선택
      │                              │          │
      │                              ▼          │
      └── 4. 대기 전환 ───────── [실행 상태] ──┘
                                     │
                              5. 실행 완료
                                     │
                                     ▼
                                 [종료 상태]
```

### 동작 원리

1. **이벤트 준비**: 인터럽트·타이머·동기화 조건이 충족된 태스크를 차단 상태에서 준비 큐로 이동한다.
2. **실행 태스크 선택**: 스케줄러가 가장 높은 우선순위의 준비 태스크를 선택하고 **문맥 전환**으로 실행 문맥을 복원한다.
3. **우선순위 선점**: 더 높은 우선순위 태스크가 준비되면 현재 문맥을 저장하고 새 태스크로 전환한다.
4. **대기 전환**: 실행 태스크가 잠금·I/O·이벤트를 기다리면 차단 상태로 이동하고 다른 준비 태스크를 선택한다.
5. **실행 완료**: 태스크 종료와 자원 해제를 TCB에 반영하고 후속 대기 태스크를 준비 상태로 전환한다.

#### 한줄 요약

- RTOS 스케줄러는 준비·실행·차단 상태를 전환하고, 더 높은 우선순위 태스크가 준비되면 현재 태스크를 선점한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **베어메탈(Bare Metal)**: 운영체제 없이 슈퍼루프와 인터럽트 코드가 하드웨어를 직접 제어하는 실행 환경이다.
- **슈퍼루프(Super Loop)**: 여러 작업을 하나의 반복문 안에서 정해진 순서로 계속 실행하는 구조이다.
- **범용 운영체제(General-purpose Operating System)**: 평균 처리량과 다양한 서비스를 중시하여 최악 지연 상한을 보장하지 않는 운영체제이다.

</details>

| 실행 환경 | RTOS | 베어메탈 | 범용 운영체제 |
|:---|:---|:---|:---|
| 적용 기준 | 다중 태스크 데드라인 입증 | 단일 제어•최소 자원 | 파일•가상 메모리•시분할 |
| 핵심 특징 | **RTOS**의 우선순위•지연 상한 분석 | **베어메탈**의 **슈퍼루프**•인터럽트 직접 제어 | **범용 운영체제**의 프로세스 시분할•풍부한 서비스 |
| 한계 | 우선순위 역전•차단•지터 | 확장 시 코드 결합 증가 | 비결정적 지연•큰 메모리 |

#### 한줄 요약

- 다중 태스크의 데드라인 분석에는 RTOS, 최소 자원의 단순 제어에는 베어메탈, 풍부한 서비스와 평균 처리량에는 범용 운영체제가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **우선순위 역전(Priority Inversion)**: 낮은 우선순위 태스크가 가진 잠금 때문에 높은 우선순위 태스크가 기다리는 현상이다.
- **우선순위 상속(Priority Inheritance)**: 잠금 보유 태스크의 우선순위를 대기 중인 높은 태스크 수준으로 올려 차단을 줄이는 기법이다.
- **지연 처리(Deferred Processing)**: ISR은 긴급 처리만 하고 나머지를 태스크 문맥으로 넘기는 방식이다.
- **스택 워터마크(Stack Watermark)**: 스택의 알려진 초기 패턴이 얼마나 덮였는지 확인하여 최대 사용량을 측정하는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **우선순위 역전**으로 높은 우선순위 태스크 장기 차단 | **우선순위 상속**과 우선순위 천장 프로토콜 적용 | 중간 우선순위 간섭을 막아 차단 시간 상한 제한 |
| ISR이 긴 작업을 수행해 고우선순위 태스크 시작 지연 | ISR은 원인만 처리하고 나머지는 **지연 처리** 태스크로 이관 | 인터럽트 점유 시간을 줄여 태스크 응답 지연 완화 |
| 인터럽트 중첩·재귀가 깊어져 태스크·ISR 스택 고갈 | 최악 중첩 깊이 분석과 **스택 워터마크** 및 보호 영역 감시 | 오버플로를 조기에 찾아 메모리 손상 방지 |
| WCET·차단·상위 간섭을 누락해 분석 밖 데드라인 위반 | 실제 우선순위와 최악 조건을 반영한 WCET·WCRT 분석·부하 시험 | 모든 태스크의 데드라인 충족 근거 확보 |

#### 한줄 요약

- WCET, 공유 자원 차단과 상위 우선순위 간섭을 포함한 WCRT가 각 태스크의 데드라인 이하인지 검증한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **스케줄 가능성(Schedulability)**: 모든 실시간 태스크가 최악 조건에서도 각자의 데드라인을 만족하는 성질이다.
- **지터(Jitter)**: 반복되는 태스크의 시작•완료 또는 응답 시간이 기준 시점에서 변하는 폭이다.
- **데드라인 충족(Deadline Satisfaction)**: 분석한 최악 응답시간(Worst-case Response Time, WCRT)이 태스크의 허용 데드라인 이하인 상태이다.
- **RTOS 선택 기준**: 다중 태스크의 스케줄 가능성과 지터 한도 및 데드라인 충족 입증 필요성으로 RTOS 적용 여부를 정하는 기준이다.

</details>

- **RTOS 선택 기준**에 따라 **스케줄 가능성**과 **지터** 한도 및 **데드라인 충족**을 입증해야 하는 다중 태스크에는 **RTOS**를 적용한다.

#### 한줄 요약

- 다중 태스크의 **WCRT≤데드라인** 입증 여부가 선택 기준이다.
