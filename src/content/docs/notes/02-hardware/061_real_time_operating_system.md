## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RTOS(Real-Time Operating System)**: 입력 이벤트 발생 시 사전에 정해진 제한 시간(마감시간, Deadline) 내에 반드시 작업을 완료하도록 보장하는 운영체제.
- **결정론적(Deterministic)**: 동일한 조건에서 시스템의 처리 지연시간과 응답 순서가 예측 가능하고 상한선(Bounded Time)이 존재하는 특성.

</details>

- 정의/개념: 작업의 논리적 정확성과 함께 정해진 마감시간(Deadline) 준수를 보장하기 위해 **선점형 스케줄링**을 제공하는 임베디드 운영체제
- 배경/필요성: 범용 OS(GPOS)의 비결정적 스케줄링 및 지연시간 한계 극복과 미션 크리티컬 제어 신뢰성 확보 필요

#### 한줄 요약
- 계산 결과가 맞는 것뿐만 아니라 정해진 시간 안에 반드시 결과를 내놓도록 보장하는 초고속 임베디드 OS다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선점형 우선순위 스케줄링(Preemptive Priority Scheduling)**: 더 높은 우선순위 태스크가 준비되면 현재 실행 중인 저순위 태스크를 즉시 중단시키고 CPU를 차지하는 방식.
- **최악 응답 시간(WCRT, Worst-Case Response Time)**: 인터럽트 지연, 문맥 교환, 락 블로킹 등을 모두 포함해 태스크 완료까지 걸릴 수 있는 최악의 시간.

</details>

- 높은 우선순위 태스크를 즉각 실행하는 **선점형 우선순위 스케줄링**
- 마이크로초 단위의 신속한 **인터럽트 지연시간(Interrupt Latency)** 및 빠른 문맥 교환
- 필수 기능만 탑재한 **초소형 마이크로커널(Microkernel)** 구조로 적은 메모리(KB 단위) 점유

#### 한줄 요약
- 우선순위가 높은 일감이 들어오면 즉시 가로채 실행하며, 수 마이크로초 안에 반응하는 결정론적 동작을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TCB(Task Control Block)**: 태스크의 실행 상태(Ready/Blocked), 레지스터 스택 포인터, 우선순위 정보를 담고 있는 커널 제어 블록.
- **IPC(Inter-Process Communication)**: 태스크 간에 큐(Queue), 세마포어(Semaphore), 뮤텍스(Mutex), 이벤트 플래그로 데이터를 동기화하는 기법.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ RTOS 커널 아키텍처 및 태스크 실행 구조                     │
│                                                             │
│  [ 하드웨어 인터럽트 (ISR) / 타이머 틱 (Tick Timer) ]       │
│  └──────────────────────────┬───────────────────────────────┘│
│                             ▼                               │
│  ┌─────────────────────────────────────────────────────────┐│
│  │ RTOS 마이크로커널                                       ││
│  │  ┌──────────────────────┐    ┌──────────────────────┐   ││
│  │  │ 선점형 스케줄러       │    │ 동기화 & IPC         │   ││
│  │  │ (우선순위 기반 큐)    │    │ (뮤텍스 / 세마포어)  │   ││
│  │  └──────────┬───────────┘    └──────────┬───────────┘   ││
│  │             ▼                           ▼               ││
│  │  ┌──────────────────────────────────────────────────┐   ││
│  │  │ TCB 관리자 & 스택 포인터 (문맥 교환 엔진)        │   ││
│  │  └──────────────────────────────────────────────────┘   ││
│  └──────────────────────────┬──────────────────────────────┘│
│                             ▼                               │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐   │
│  │ 태스크 A     │    │ 태스크 B     │    │ 태스크 C     │   │
│  │ (긴급 제어)  │    │ (통신 처리)  │    │ (배경 로깅)  │   │
│  └──────────────┘    └──────────────┘    └──────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 인터럽트가 발생하면 스케줄러가 TCB 우선순위 큐를 평가해 가장 긴급한 태스크로 문맥 교환 수행

| 구성요소 | 책임 |
|:---|:---|
| 선점형 스케줄러 | Ready 큐에서 가장 높은 우선순위 태스크를 선택해 CPU 실행권 부여 |
| TCB & 문맥 교환기 | 태스크 레지스터 상태를 스택에 저장/복원하여 마이크로초 단위 빠른 전환 |
| 동기화 및 IPC 모듈 | 뮤텍스(Mutex), 메시지 큐, 세마포어로 태스크 간 안전한 데이터 교환 보장 |
| 타이머 및 지연 관리자 | 주기적 틱(Tick) 인터럽트를 통해 시간 지연(Delay) 및 타임아웃 관리 |
| 메모리 관리자 | 메모리 단편화를 방지하기 위해 고정 크기 블록(Fixed-size Pool) 할당 |

#### 한줄 요약
- 스케줄러, TCB 문맥 교환기, IPC 동기화 엔진, 타이머, 고정 메모리 풀이 마이크로커널의 뼈대를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 전이(State Transition)**: 태스크가 Ready(준비), Running(실행), Blocked(대기/지연), Suspended 상태 간을 오가는 과정.

</details>

```text
외부 센서 하드웨어 인터럽트 발생
      │
      ▼
1. ISR 실행: 인터럽트 서비스 루틴에서 최소 데이터 수집 후 태스크 시그널 전송
      │
      ▼
2. 태스크 Ready 전이: 대기 중이던 고우선순위 제어 태스크가 Ready 큐로 진입
      │
      ▼
3. 선점형 스케줄링: 현재 실행 중인 저우선순위 태스크를 중단하고 문맥(Context) 저장
      │
      ▼
4. 고우선순위 태스크 디스패치: 제어 알고리즘 연산 실행 및 PWM 출력
      │
      ▼
5. 태스크 완료 및 복귀: 고우선순위 태스크가 Blocked 상태로 전환되며 이전 태스크 재개
```

**동작 원리**

1. **인터럽트 진입**: 센서 인터럽트 발생 시 CPU가 ISR로 분기하여 세마포어나 큐에 이벤트 포스팅
2. **우선순위 평가**: ISR 종료 시점에 스케줄러가 대기 중이던 최우선 태스크의 준비 상태 감지
3. **선점 및 문맥 저장**: 현재 동작 중인 태스크의 CPU 레지스터를 TCB 스택에 저장하고 선점
4. **목표 작업 실행**: 긴급 태스크가 즉각 실행되어 마감시간 이내에 제어 알고리즘 출력 완료
5. **이전 작업 복귀**: 작업 종료 후 다음 순위 태스크의 레지스터를 복원하여 중단된 지점부터 재개

#### 한줄 요약
- 인터럽트 감지 → Ready 큐 등록 → 선점 및 문맥 교환 → 긴급 태스크 실행 → 이전 작업 복귀 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 운영체제 아키텍처 | RTOS (실시간 OS) | GPOS (범용 OS) | 베어메탈 (No OS) | 임베디드 리눅스 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 미션 크리티컬 차량·항공·의료 제어 | PC·스마트폰 멀티미디어·사무용 | 극소형 초저가 가전 센서 노드 | 스마트 게이트웨이·복잡한 통신 장비 |
| 핵심 특징 | 선점형 우선순위 스케줄링 및 결정론적 응답 | 공정성(Fairness) 기반 시분할 및 높은 처리율 | OS 없이 메인 무한 루프 직접 폴링 | 광범위한 드라이버 지원 및 오픈소스 |
| 한계 | 지원 라이브러리 및 복잡한 GUI 부재 | 비결정적 지연(지연시간 예측 불가) | 코드 복잡도 증가 시 유지보수 한계 | 실시간성 보장 불가(PREEMPT_RT 필요) |

#### 한줄 요약
- 마감시간이 생명인 곳은 RTOS, 범용 편의성은 GPOS, 단순 제어는 베어메탈, 복합 통신은 임베디드 리눅스를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 중간 순위 태스크가 실행되면서 자원을 쥐고 있는 저순위 태스크를 가로채 고순위 태스크가 무한정 대기하는 버그.
- **우선순위 상속(Priority Inheritance)**: 공유 자원을 획득한 저순위 태스크의 우선순위를 자원을 기다리는 고순위 태스크 수준으로 임시 승격시키는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 점유로 인한 **우선순위 역전(Priority Inversion) 발생** | **우선순위 상속(Priority Inheritance) 프로토콜** 뮤텍스 적용 | 고우선순위 태스크의 무한 지연 원천 차단 |
| 잦은 문맥 교환으로 인한 **CPU 오버헤드 증가** | ISR 내 직접 연산 배제(Defer) 및 태스크 통합 최적화 | 시스템 가용 처리율 20% 이상 개선 |
| 태스크 스택 메모리 부족으로 인한 **스택 오버플로우(Stack Overflow)** | **스택 워터마크(High-Watermark)** 감시 및 MPU 하드웨어 가드 설정 | 메모리 침범 방지 및 즉각 예외 트랩 |
| 동적 메모리 할당(malloc) 시 **메모리 단편화 및 불확정 지연** | **고정 크기 메모리 풀(Memory Pool)** 사전 정적 할당 사용 | 결정론적 $O(1)$ 시간 메모리 할당 보장 |

#### 한줄 요약
- 우선순위 상속으로 역전을 막고, 스택 가드로 충돌을 잡으며, 고정 메모리 풀로 단편화를 없앤다.

## Ⅶ. 결론

- 항공·자동차·의료 등 안전 필수 임베디드 제어는 **인증된 상용/오픈소스 RTOS (FreeRTOS, VxWorks, QNX)** 필수 선택

#### 한줄 요약
- 선점형 우선순위 스케줄링과 우선순위 상속 프로토콜을 철저히 준수하여 결정론적 실시간 응답을 달성해야 한다.
