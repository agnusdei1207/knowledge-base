## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 운영체제(Real-Time Operating System)**: 태스크 응답시간을 예측하고 마감시간(Deadline) 내에 결과를 반환하는 결정론적(Deterministic) 시간 보장성을 뼈대로 삼는 군대 같은 운영체제이다.
- **태스크(Task)**: 에어백 터뜨리기, 라디오 틀기처럼 커널 스케줄러에 의해 계급(우선순위)이 매겨져 통제받는 독립적인 훈련병들이다.
- **데드라인(Deadline)**: 차가 벽에 박았을 때 0.01초 안에 에어백이 터져야 한다는, 단 0.001초라도 늦으면 사람이 죽을 수 있는 얄짤없는 시간제한이다.

</details>

- 정의: 우선순위 깡패 스케줄링과 지연 상한 분석을 통해 무조건 정해진 시간 안에 결과를 내놓는 **실시간 운영체제**
- 배경: 윈도우나 리눅스 같은 범용 OS(GPOS)는 자기가 바쁘면 "잠깐만" 하고 딜레이 시키는 비결정성이 있어, 에어백 같은 생명 직결 시스템에 쓰면 사람이 죽기 때문

#### 한줄 요약

- 윈도우처럼 버벅거리다 블루스크린 띄우는 게 아니라, 에어백이 터지는 0.01초의 마감시간을 목숨 걸고 지키기 위해 만들어진 깐깐한 독재 운영체제이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **결정성(Determinism)**: 평균 속도가 얼마나 빠른지는 관심 없고, 재수가 옴 붙은 "최악의 상황에서도 이 시간 안에는 반응한다"는 보장성이다.
- **최악 실행 시간(Worst-Case Execution Time, WCET)**: if 문을 수백 번 타서 태스크가 가장 뺑뺑이를 많이 돌았을 때 걸리는 최악의 퓨어 연산 시간이다.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 내 연산 시간에 남한테 방해받아 멈춰있던 시간까지 몽땅 더해, 실제로 최종 결과가 나오는 가장 끔찍한 소요 시간이다.
- **우선순위 선점(Priority-Based Preemption)**: 라디오(낮은 계급)를 틀고 있다가 에어백 센서(높은 계급)가 들어오면, 라디오를 가차 없이 발로 차버리고 CPU를 뺏어버리는 깡패 짓이다.

</details>

- 평균적으로 빠른 것보다, 최악의 상황에서도 무조건 이 시간 안에는 반응한다는 **결정성** 및 **최악 응답 시간**(WCRT)을 절대적으로 보장함.
- 중요한 일(에어백)이 터지면 덜 중요한 일(라디오)을 가차 없이 중단시키고 뺏어버리는 **우선순위 선점** 기반 스케줄링을 강제함.
- 순수 연산 시간(**최악 실행 시간**, WCET)에 남이 방해하는 시간까지 몽땅 더해 마감시간 내에 끝나는지 수학적으로 입증함.

$$
R_i^{(k+1)} =
C_i + B_i +
\sum_{j \in hp(i)}
\left\lceil \frac{R_i^{(k)}}{T_j} \right\rceil C_j
$$

#### 한줄 요약

- 평소에 0.001초 만에 끝나도 어쩌다 1초가 걸리면 실격이며, 무슨 짓을 해도(최악 응답 시간) 반드시 0.01초(데드라인) 안에 끝난다는 수학적 보장이 생명이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 센서에 불이 들어오면 하던 걸 다 내팽개치고 가장 먼저 튀어 나가 처리하는 0순위 특수부대이다.
- **태스크 제어 블록(Task Control Block, TCB)**: CPU에서 쫓겨난 태스크가 "나 여기까지 했음"이라고 현재 상태와 계급을 적어놓는 호적등본이다.
- **준비 큐(Ready Queue)**: 잠에서 깨어나 CPU를 배정받기 위해 태스크들이 계급순으로 살벌하게 서 있는 대기 줄이다.
- **동기화 관리(Synchronization Management)**: 두 놈이 하나의 램(RAM)을 찢어 먹지 못하게, 한 놈이 쓸 때 방문을 잠가버리는 신호등(뮤텍스/세마포어)이다.

</details>

```text
[ 실시간 운영체제 커널의 살벌한 스케줄링 및 멱살 잡기 프레임워크 ]
[ 인터럽트 특수부대 (ISR) ] ▶ [ 준비 큐 (계급순 대기열) & TCB (호적등본) ]
                                   │
                     +-------------+-------------+
                     ▼                           ▼
        [ 무자비한 스케줄러 ]            [ 동기화 관리 (신호등) ]
      (높은 계급이 오면 기존 놈 킥)     (뮤텍스로 메모리 방어)
```

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 관리 | 하드웨어 센서에 불이 들어오면 모든 걸 제쳐두고 가장 먼저 튀어 나가 처리하는 0순위 특수부대(**인터럽트 서비스 루틴**) |
| **태스크 제어 블록** 및 큐 | 누가 대기 중인지 줄을 세우는 **준비 큐**와, 그놈의 현재 상태를 적어놓은 호적등본(**태스크 제어 블록**) |
| 실시간 스케줄러 | 대기 줄을 무시하고 VIP(고우선순위)가 오면 기존 놈을 걷어차고 CPU를 빼앗아버리는 권력자 |
| **동기화 관리** | 두 태스크가 하나의 램(RAM)을 동시에 물고 뜯지 않게 질서를 잡아주는 신호등(뮤텍스/세마포어) |

#### 한줄 요약

- 센서가 울리면(인터럽트), 줄을 서고(준비 큐), 대장(스케줄러)이 제일 높은 놈에게 CPU를 주며, 서로 싸우지 않게 신호등(동기화)을 켜준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **준비 상태(Ready State)**: 준비 운동 다 끝내고 스케줄러가 내 이름만 불러주길 애타게 기다리며 줄 서 있는 벤치 멤버 상태이다.
- **문맥 전환(Context Switch)**: 쓰던 태스크를 쫓아낼 때 현재 뇌 상태(레지스터)를 TCB에 백업하고, 새 태스크의 뇌를 복원하는 뇌 이식 수술이다.
- **차단 상태(Blocked State)**: 내가 쓰려는 메모리를 딴 놈이 쓰고 있어서, 방 빼줄 때까지 강제로 손들고 서 있는 징벌 방(유배) 상태이다.

</details>

```text
[ 실시간 운영체제 태스크 멱살 잡기 및 상태 전환 스케줄링 흐름 ]
                         ┌──────────────────────┐
                         │ [ 3. 더 높은 놈 등장 시 걷어차기 (선점) ]
                         │                      │
                         ▼                      │
[차단 상태(유배)] ── 1. 센서 쾅! ──► [준비 상태(줄서기)]
      ▲                              │          │
      │                              │          │
      │                  2. 1등 놈 멱살 잡고 뇌 이식 (문맥 전환)
      │                              │          │
      │                              ▼          │
      └── 4. 남의 자원 건드림 ──── [실행 상태(CPU)] ─┘
                                     │
                             5. 연산 종료 (방 뺌)
                                     │
                                     ▼
                                 [종료 상태]
```

### 동작 원리

1. 이벤트 발생 및 대기: 외부 센서가 터지면 잠자던 태스크가 깨어나 CPU 할당을 기다리는 **준비 상태**로 진입함.
2. 1등 태스크 CPU 할당: 스케줄러가 줄 서 있는 놈들 중 계급(우선순위)이 제일 높은 놈의 멱살을 잡아 CPU에 꽂아 넣음.
3. 무자비한 우선순위 선점: 실행 도중 더 높은 계급이 등장하면, 얄짤없이 뇌 상태를 저장(**문맥 전환**)하고 쫓아냄.
4. 남의 자원 대기 차단: 쓰려던 메모리를 남이 쓰고 있으면 강제로 멈춰 세우는 **차단 상태**로 유배를 보냄.
5. 연산 종료 및 찌꺼기 해제: 연산이 무사히 끝나면 빌려 쓴 메모리를 반납하고 다음 명령을 대기함.

#### 한줄 요약

- 줄 서 있다가(준비), 1등이면 CPU를 먹는데(실행), 더 높은 놈이 오면 뺏기고(선점), 남의 거 건드리면 감옥(차단)에 간다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **베어메탈(Bare Metal)**: 운영체제 따위 사치라며 다 걷어내고, 밥솥 회로처럼 무한 루프(while(1)) 돌면서 센서만 쳐다보는 극단적 깡통 펌웨어이다.
- **범용 운영체제(General-Purpose OS, GPOS)**: 윈도우나 리눅스처럼 누구 하나 독점하지 못하게 시간을 쪼개서(시분할) 여러 프로그램을 공평하게 돌려주는 민주주의 시스템이다.

</details>

| 실행 환경 | **실시간 운영체제** (RTOS) | **베어메탈** (Bare Metal / 무한 루프) | **범용 운영체제** (GPOS) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 자동차 브레이크, 미사일 궤적 제어처럼 단 0.001초라도 늦으면 사람이 죽거나 파국이 나는 살벌한 환경 | 밥솥이나 에어컨 리모컨처럼 칩이 작고 기능이 몇 개 없어 굳이 운영체제까지 깔 필요 없는 단순 깡통 기계 | 컴퓨터, 스마트폰, 서버처럼 공평하게 이것저것 여러 프로그램을 띄워놓고 멀티 딴짓을 해야 하는 환경 |
| 아키텍처 핵심 구현 특징 | 덜 중요한 놈을 걷어차고 중요도 순으로 줄을 세워 무조건 마감시간을 지켜버리는 독재적 스케줄링 | 운영체제 없이 무한 루프(While)만 팽팽 돌면서 하드웨어 인터럽트만 쳐다보고 있는 극단적 단순 무식 구조 | 누구 하나 독점하지 않게 시간을 쪼개서(시분할) 공평하게 나눠 쓰며, 화려한 UI와 스토리지 관리 기능 내장 |
| 극복해야 할 태생적 한계점 | 깐깐하게 줄 세우고 뇌 이식(문맥 전환) 하느라 버리는 시간(오버헤드)이 생기고 메모리(RAM)를 꽤나 잡아먹음 | 프로그램 덩치가 조금만 커져도 코드가 꼬여 스파게티가 되어버려 유지보수 및 업그레이드가 불가능한 치명적 제약 | 자기가 바쁘면 마감시간을 안 지키고 버벅거려서, 브레이크나 에어백 같은 생명 직결 제어기에는 절대 못 쓰는 비결정성 한계 |

#### 한줄 요약

- 목숨이 달렸으면 마감시간을 지키는 RTOS를 쓰고, 밥솥처럼 싸고 단순하면 베어메탈을 쓰며, 웹서핑이나 영화를 보려면 리눅스(GPOS)를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 역전(Priority Inversion)**: 하사관(하순위)이 메모리 방 열쇠를 쥐고 안 놔주는 바람에, 장군(상순위)이 방에 못 들어가고 복도에서 벌벌 떠는 기가 막힌 하극상이다.
- **우선순위 상속(Priority Inheritance)**: 장군이 밖에서 기다리다 빡치면, 임시로 하사관에게 장군 계급장을 빌려줘서 빨리 일을 끝내고 열쇠를 뱉게 만드는 꼼수 해결책이다.
- **스택 워터마크(Stack Watermark)**: 태스크가 지한테 할당된 메모리 선을 넘어 침범했는지 확인하려고, 메모리 끝자락에 'DEADBEEF' 같은 가비지 패턴을 채워 넣고 감시하는 지뢰밭이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하급자가 메모리를 물고 안 놔줘서 상급자가 일을 못 하고 대기 타는 하극상 대참사(**우선순위 역전**) 발발 | 하급자에게 잠시 상급자 계급장을 빌려줘서 빨리 일을 끝내고 메모리를 뱉게 만듦(**우선순위 상속**) | 엉뚱한 대기로 인해 최악 응답 시간(WCRT)이 뻥튀기되어 마감시간을 놓치는 대사태 완벽 차단 |
| 스케줄러가 너무 자주 태스크를 걷어차고 뇌 이식(문맥 전환) 하느라 실제 일은 못 하고 낭비되는 오버헤드 | 자질구레한 태스크를 하나로 합치고 급하지 않은 일은 나중에 처리하도록 지연 처리(Deferred Processing) 스케줄링 강제 | 스케줄러 뻘짓을 줄여 칩셋의 실제 퓨어 연산 CPU 활용률을 극한으로 쥐어짜는 최적화 달성 |
| 태스크가 지한테 할당된 램 선을 넘어 남의 구역까지 덮어써 버려 커널을 박살 내는 오버플로우 폭파 | 메모리 끝자락에 가비지 패턴을 채워 넣고 침범했는지 감시하는 깐깐한 **스택 워터마크** 모니터링 수용 | 메모리 오염으로 시스템이 원인도 모르게 뻗어버리는 끔찍한 셧다운 미스터리 원천 봉쇄 |

#### 한줄 요약

- 하극상을 막기 위해 계급장을 빌려주고(우선순위 상속), 쓸데없는 자리 바꾸기를 줄이며(문맥 전환 최소화), 남의 메모리를 침범하는 놈(오버플로우)을 감시해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **운영체제 선정 기준(OS Selection Criteria)**: 이 기계가 버벅거렸을 때 사람이 다치는지, 그냥 욕 한 번 먹고 말지를 따져 칩에 무슨 OS를 올릴지 결정하는 살벌한 기준표이다.

</details>

- **운영체제 선정 기준**에 따라 단 0.001초의 딜레이도 용납 안 되는 전장·항공 시스템엔 무조건 **실시간 운영체제**(RTOS) 채택을 단호히 결정함
