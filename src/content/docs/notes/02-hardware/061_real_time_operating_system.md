## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 운영체제(Real-Time Operating System, RTOS)**: 태스크의 시간 제약을 분석하고 마감시간 준수를 우선하는 운영체제.
- **결정론적 응답성(Deterministic Responsiveness)**: 실행·블로킹·간섭 시간을 분석해 응답 시간 상한을 예측할 수 있는 특성.

</details>

- 정의/개념: 태스크의 마감시간 준수를 우선하는 **실시간 운영체제(RTOS)**
- 배경/필요성: 범용 OS(GPOS)의 평균 처리량 중심 비선점 구간 및 페이징 지연으로 인한 **응답 시간 불확정성(Non-deterministic Jitter) 및 마감시간 초과 위험**

#### 한줄 요약
- RTOS는 평균 처리 속도가 아닌 최악 응답 시간(WCRT)의 상한을 보장하여 시스템의 실시간 결정성을 확보하는 운영체제이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **선점형 우선순위 스케줄링(Preemptive Priority Scheduling)**: 더 높은 우선순위 태스크가 Ready 상태가 되는 즉시 현재 실행 중인 저순위 태스크를 가로채고 CPU 제어권을 즉각 획득하는 메커니즘.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 인터럽트 지연, 문맥 교환, 락 블로킹을 모두 포함하여 태스크가 완료되기까지 소요될 수 있는 최대 지연시간.

</details>

- 결정론적 스케줄링: 선점형 우선순위로 고순위 태스크의 대기 시간 상한 분석
- 커널 지연 통제: 임계 구역과 인터럽트 차단 시간을 줄여 **WCRT** 상한 관리
- 메모리 결정성: 정적 메모리 풀로 할당 지연과 단편화 변동 억제

#### 한줄 요약
- **선점형 우선순위 스케줄링**, 최소 인터럽트 지연, 정적 메모리 풀을 통해 시간적 결정론을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **태스크 제어 블록(Task Control Block, TCB)**: 태스크의 실행 상태(Ready/Running/Blocked), 스택 포인터(SP), 우선순위, 레지스터 문맥을 보관하는 커널 핵심 데이터 구조.
- **프로세스 간 통신(Inter-Process Communication, IPC)**: 큐(Queue), 세마포어(Semaphore), 뮤텍스(Mutex), 이벤트 플래그를 통해 태스크 간 동기화와 데이터 교환을 수행하는 메커니즘.
- **우선순위 상속(Priority Inheritance Protocol, PIP)**: 공유 자원을 획득한 저순위 태스크의 우선순위를 해당 자원을 기다리는 고순위 태스크 수준으로 임시 승격시키는 기법.

</details>

```text
[RTOS 마이크로커널 아키텍처]
  │
  ├─ [사용자 애플리케이션 계층] (실시간 태스크군)
  │     ├─ [긴급 제어 태스크] (최고 우선순위 주기 태스크)
  │     ├─ [통신 처리 태스크] (중간 우선순위 이벤트 태스크)
  │     └─ [배경 로깅 태스크] (최저 우선순위 유휴 태스크)
  │
  ├─ [RTOS 마이크로커널 엔진] (결정론적 커널 계층)
  │     ├─ [선점형 스케줄러] (O(1) 우선순위 탐색 큐)
  │     ├─ [문맥 교환기] (TCB 스택/레지스터 대피 및 복원)
  │     ├─ [동기화 & IPC 모듈] (뮤텍스 PIP 상속, 세마포어)
  │     └─ [정적 메모리 풀] (고정 크기 블록 할당 단편화 방지)
  │
  └─ [하드웨어 추상화 계층] (HAL 및 SoC 인터페이스)
        ├─ [NVIC 인터럽트 컨트롤러] (하드웨어 중첩 인터럽트)
        └─ [SysTick 타이머] (결정론적 커널 시스템 틱 공급)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 선점형 스케줄러 | 우선순위 큐에서 실행 태스크 선택 |
| TCB 관리자 | 태스크 상태·스택·레지스터 문맥 보관 |
| **IPC** 동기화 모듈 | 큐·세마포어·**우선순위 상속** 제공 |
| 정적 메모리 풀 | 고정 블록으로 할당 지연 변동 억제 |
| 시스템 타이머 | 주기 실행과 타임아웃 기준 제공 |

#### 한줄 요약
- 정적 메모리 풀이 요청마다 빈 공간을 찾아다니던 동적 할당을 고정 블록 배분으로 갈아치워 할당 시간의 상한을 확정하고, 시스템 타이머는 그 상한을 지켰는지 판정할 공통 시간 기준을 스케줄러에 공급한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **선점(Preemption)**: 실행 중인 저우선순위 태스크의 CPU 점유를 강제로 중단시키고 고우선순위 태스크로 제어권을 즉각 넘기는 메커니즘.
- **문맥 교환(Context Switch)**: CPU 레지스터, 스택 포인터 등 현재 태스크의 실행 상태(TCB)를 메모리에 저장하고 새 태스크의 문맥을 복원하는 과정.

</details>

```text
[외부 센서 이벤트 및 하드웨어 인터럽트 인입]
                     │
                     ▼
1. 인터럽트 컨트롤러(NVIC)의 최우선 하드웨어 ISR 즉각 분기
                     │
                     ▼
2. ISR의 대기 태스크 Ready 상태 전이 및 우선순위 비교
    ┌────────────────┴────────────────┐
 [ 현재 실행 태스크보다 낮음 ]       [ 현재 태스크보다 고순위 ]
    │                                 │
    ▼                                 ▼
Ready 큐에 정렬 대기 유지             3. 현재 태스크 문맥(TCB) 스택 저장 및 선점(Preemption) 단행
    │                                 │
    │                                 ▼
    │                              4. 공유 자원(뮤텍스) 점유 상태 검증
    │                                 ┌───────┴───────┐
    │                              [ 즉시 획득 ]   [ 저순위 태스크 점유 중 ]
    │                                 │               │
    │                                 ▼               ▼
    │                              즉시 제어 연산   우선순위 상속(PIP) 발동 ➔ 신속 해제 유도
    │                                 │               │
    │                                 └───────┬───────┘
    │                                         │
    ▼                                         ▼
5. 제어 출력 완수 및 차순위 태스크 문맥 복원(Context Restore)
```

- 분기 결과: 고순위 태스크 도착 시 저순위 태스크를 즉각 선점하며, 뮤텍스 충돌 시 우선순위 상속(PIP)을 발동하여 우선순위 역전 지연을 차단함

**동작 원리**

1. 센서 트리거 발생 시 CPU 하드웨어의 NVIC 인터럽트 벡터 테이블 참조 및 인터럽트 서비스 루틴(ISR) 제어권 즉각 이양
2. ISR의 세마포어 해제를 통한 실시간 제어 태스크 Ready 큐 이동 및 커널 스케줄러 스케줄링 플래그 설정
3. 스케줄러의 Ready 큐 헤드 검사 후 고우선순위 확인 시 기존 레지스터 TCB 백업 및 즉각적 문맥 교환 단행
4. 공유 자원 접근 경합 발생 시 PIP(우선순위 상속) 발동을 통한 저순위 태스크 우선순위 일시 승격 및 자원 해제 가속화
5. 마감시간 내 제어 연산 및 물리 출력 완수 후 슬립 전이 및 백업 TCB 복원을 통한 원래 태스크 복귀 수행

#### 한줄 요약
- 선점은 응답성을 사기 위해 이벤트마다 문맥 전환 비용을 지불하는 선택이므로, 우선순위 설계가 어긋나면 PIP로 되막아야 할 역전 구간을 스케줄러가 스스로 만들어 낸다.

## Ⅴ. 종류 및 비교

| 대상 구분 | RTOS (FreeRTOS, VxWorks, QNX) | 범용 OS (Linux, Windows) | 임베디드 Linux (PREEMPT_RT) |
|:---|:---|:---|:---|
| 적용 기준 | 초 단위 이하 결정론적 마감시간 엄격 준수 및 하드 실시간 제어 요구 시 | 다양한 응용 소프트웨어 호환성 및 대규모 처리량 극대화 요구 시 | 리눅스 네트워크/미디어 스택을 활용하며 준실시간 제어 요구 시 |
| 핵심 특징 | 선점형 우선순위 스케줄러, 정적 메모리 풀, 결정론적 WCRT 상한 보장, 마이크로초($\mu\text{s}$) 단위 즉각 응답 | CFS/다단계 피드백 스케줄러, MMU 기반 가상 메모리 및 요구 페이징, 대규모 I/O 처리량 극대화 | 메인라인 실시간 패치 커널, 인터럽트 스레드화 및 스핀락 뮤텍스 변환, 지연 변동성 완화 |
| 한계 | 범용 드라이버 및 애플리케이션 생태계 부족, 고비용 상용 라이선스 | 비선점 커널 구간 및 페이지 폴트로 인한 지연 변동(Jitter) 심화로 하드 실시간 보장 불가 | 마이크로초 단위 엄격한 하드 실시간 보장 한계 및 커널 풋프린트 증가 |

#### 한줄 요약
- 마감시간 준수가 생명인 제어 시스템에는 RTOS가 필수이며, 복잡한 통신과 멀티미디어 처리에는 임베디드 리눅스가 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **우선순위 천장 프로토콜(Priority Ceiling Protocol, PCP)**: 각 뮤텍스에 접근 가능한 최고 태스크의 우선순위를 천장값으로 부여하여 연쇄 블로킹과 데드락을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 자원 경합에 따른 우선순위 역전 | **우선순위 상속(PIP)** 및 **우선순위 천장(PCP)** 적용 | 고순위 태스크의 블로킹 시간 상한선 보장 |
| 잦은 문맥 교환으로 인한 인터럽트 오버헤드 | **ISR 상·하반부 분리(Top/Bottom-Half)** 기법 적용 | 인터럽트 마스킹 시간 최소화 |
| 태스크 스택 오버플로로 인한 메모리 오염 | **하드웨어 MPU** 스택 보호 영역 설정 | 스택 침범 감지 시 즉각 예외 트랩 발생 |

#### 한줄 요약
- 실무에서는 PIP/PCP로 우선순위 역전을 잡고, ISR 분리로 지연을 줄이며, MPU로 스택 침범을 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실시간 선점 리눅스 패치(Real-Time Preemption Patch, PREEMPT_RT)**: 리눅스 커널의 스핀락과 인터럽트 핸들러를 선점 가능한 스레드로 전환하여 커널 지연 변동성을 극소화하는 실시간 확장 기능.
- **가상화 하이퍼바이저(Virtualization Hypervisor)**: 단일 SoC 상에서 하드 실시간 RTOS와 범용 운영체제를 하드웨어 수준에서 격리하여 동시 구동하는 가상화 계층.
- **범용 운영체제(General Purpose Operating System, GPOS)**: 엄격한 마감시간 준수보다 평균 처리량과 풍부한 애플리케이션 생태계를 우선하는 운영체제.
- **메모리 보호 장치(Memory Protection Unit, MPU)**: 태스크별 메모리 접근 권한을 감시하여 스택 오버플로 및 불법 메모리 침범을 차단하는 하드웨어 유닛.

</details>

- 하드 실시간 결정론성을 보장하는 전용 RTOS 생태계의 성숙과 함께, PREEMPT_RT 기반 실시간 리눅스 및 하이퍼바이저 가상화를 활용한 이종 멀티코어 단일 칩 통합 아키텍처로의 진화 추세.
- 최악 응답 시간(WCRT) 분석을 통한 정적 스케줄링 적합성 검증과 더불어, 우선순위 역전 방지 프로토콜 및 하드웨어 MPU 결함 격리를 결합한 무결성 아키텍처 확보 필요.

#### 한줄 요약
- 이종 멀티코어 가상화 환경에서 결정론적 WCRT 상한 보장과 하드웨어 격리를 통해 실시간성과 범용 처리량을 동시에 달성해야 한다.
