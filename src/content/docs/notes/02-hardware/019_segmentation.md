## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 코드·데이터·스택처럼 의미가 있는 가변 크기 단위로 나누는 메모리 관리 기법입니다.
- **논리 주소(Logical Address)**: 세그먼트 식별자와 세그먼트 내부 오프셋으로 표현한 프로그램 관점의 주소입니다.
- **메모리 보호(Memory Protection)**: 세그먼트별 접근 권한과 범위로 허가되지 않은 메모리 사용을 막는 기능입니다.

</details>

- 정의/개념: 논리 단위를 기준 주소와 한계로 변환·보호하는 **가변 분할 메모리 기법**
- 배경/필요성: 코드·데이터·스택별 보호와 공유 경계 제공

#### 한줄 요약

- 프로그램의 의미 단위마다 시작점과 크기를 따로 기록해, 각 영역을 독립적으로 보호하고 배치하는 방식입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기준 주소(Base)**: 세그먼트가 실제 메모리에서 시작하는 위치입니다.
- **한계(Limit)**: 세그먼트 내부에서 허용되는 오프셋의 최대 범위입니다.
- **외부 단편화(External Fragmentation)**: 빈 공간 총량은 충분하지만 연속된 큰 공간이 없어 할당하지 못하는 현상입니다.

</details>

- 기준 주소와 **한계 검사**에 따른 영역 보호
- 논리 단위별 **독립 성장**과 공유
- 가변 할당에 따른 **외부 단편화**

#### 한줄 요약

- 필요한 크기만 영역으로 만들 수 있는 대신, 영역을 자주 만들고 없애면 메모리 사이에 작은 빈틈이 남습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 기준 주소, 한계, 접근 권한, 유효 상태를 기록한 표 항목입니다.
- **세그먼트 테이블(Segment Table)**: 프로세스가 사용할 세그먼트 기술자들을 모아 둔 테이블입니다.
- **주소 생성기(Address Generator)**: 기준 주소에 오프셋을 더해 선형 주소를 만드는 회로입니다.

</details>

```text
[세그멘테이션]
├─ 세그먼트 선택자
├─ 세그먼트 테이블
│  └─ 기술자: Base·Limit·권한
├─ 보호 검사기
└─ 주소 생성기
```

| 구성요소 | 책임 |
|:---|:---|
| 세그먼트 선택자 | 사용할 논리 영역 지정 |
| 세그먼트 테이블 | 기준·한계·권한 정보 제공 |
| 보호 검사기 | 오프셋 범위와 접근 권한 판정 |
| 주소 생성기 | 기준 주소와 오프셋으로 선형 주소 생성 |

#### 한줄 요약

- 선택자로 영역을 고르고 기술자에서 기준·크기·권한을 읽은 뒤, 검사기를 통과한 주소만 실제 접근에 사용합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보호 예외(Protection Fault)**: 세그먼트 범위나 접근 권한을 위반했을 때 발생하는 동기 예외입니다.
- **선형 주소(Linear Address)**: 세그먼트 변환 뒤 페이징 입력으로 사용되는 주소입니다.

</details>

```text
[1. 선택자·오프셋 입력]
          │
          ▼
[2. 기술자 조회]
          │
          ▼
[3. 권한·한계 검사]
          │
          ├─ 실패 → [보호 예외]
          │
          └─ 통과 → [4. 선형 주소 생성]
```

동작 원리:

1. 선택자·오프셋 입력: 논리 주소의 세그먼트와 내부 위치 확인
2. 기술자 조회: 세그먼트 테이블에서 메타데이터 확보
3. 권한·한계 검사: 접근 종류와 오프셋 범위 검증
4. 선형 주소 생성: 기준 주소와 오프셋을 더해 다음 주소 생성

#### 한줄 요약

- 영역의 이름을 찾고 접근 권한과 범위를 확인한 뒤에만 그 영역 안의 실제 위치를 계산합니다.

## Ⅴ. 종류 및 비교

| 메모리 분할 방식 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 적용 기준 | 논리 단위 보호·공유 우선 | 고정 단위와 비연속 배치 우선 |
| 핵심 특징 | 가변 세그먼트와 Base·Limit | 고정 페이지와 프레임 매핑 |
| 한계 | 외부 단편화와 가변 할당 비용 | 내부 단편화와 페이지 테이블 비용 |

#### 한줄 요약

- 세그멘테이션은 프로그램 의미를 잘 보존하고, 페이징은 물리 메모리를 관리하기 쉽다는 차이가 있습니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 페이지(Guard Page)**: 접근 불가 페이지를 경계에 배치해 스택 오버플로를 예외로 감지하는 기법입니다.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 주소 변환 결과를 저장해 변환 지연을 줄이는 캐시입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 영역 할당·해제로 외부 단편화 증가 | 페이징 결합과 비연속 프레임 배치 | 큰 연속 공간 의존 완화 |
| 스택 확장이 인접 영역 침범 | 가드 페이지와 세그먼트 권한 적용 | 오버플로 조기 감지 |
| 영역별 권한 설정 오류 | 코드·데이터·스택 권한 분리 검증 | 비허가 접근 차단 |
| 기술자 조회가 주소 변환 지연 유발 | TLB에 변환 결과 저장 | 반복 변환 지연 감소 |

#### 한줄 요약

- 현대 시스템은 세그먼트의 논리적 보호 장점을 남기면서, 페이징과 TLB로 가변 배치와 변환 비용을 보완합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **평면 주소 모델(Flat Address Model)**: 세그먼트별 주소 계산을 최소화하고 하나의 선형 주소 공간을 사용하는 모델입니다.

</details>

- 논리 단위 권한과 공유가 핵심이면 **세그멘테이션**을 활용하고, 외부 단편화·관리 단순성이 우선이면 페이징과 평면 주소 모델을 중심으로 결정

#### 한줄 요약

- 세그멘테이션은 논리적 보호가 필요한 곳에 의미가 있고, 범용 시스템은 관리 비용이 낮은 페이징을 기본으로 선택하는 방향입니다.
