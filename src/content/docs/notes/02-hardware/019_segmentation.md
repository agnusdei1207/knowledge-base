## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 의미론적 성격이 같은 논리적 단위인 가변 크기의 세그먼트로 나누어 관리하는 기법이다.
- **논리 권한 경계(Logical Permission Boundary)**: 코드, 데이터, 스택 등 각 논리 구역별로 부여된 특화된 메모리 접근 제어 한계선이다.
- **평면 주소 공간(Flat Address Space)**: 논리 구분 없이 시작부터 끝 번지까지를 하나의 단일 연속 일직선 메모리로 취급하는 구조이다.

</details>

- 정의: 가상 주소 공간을 논리적 가변 영역으로 분할하여 주소 변환과 보호를 수행하는 **세그멘테이션** 관리 기법
- 배경: 영역별 권한 경계가 없을 때 발생하는 코드 및 스택 침범과 메모리 보호 취약성을 하드웨어 수준에서 방어하기 위함

#### 한줄 요약

- 가상 메모리를 논리 모듈 단위로 분할하여 독립된 기준 주소 및 한계값을 기반으로 효율적인 주소 변환과 보호를 제공하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **2차원 주소(Two-Dimensional Address)**: 선택자와 오프셋 2개의 매개변수로 구성되어 논리 구조를 직접 참조하는 주소 지정 방식이다.
- **기준 주소(Base Address)**: 해당 세그먼트 영역이 주기억장치에서 시작되는 물리적 바이트 시작 번지이다.
- **한계(Limit)**: 가상 공간의 세그먼트가 물리 메모리상에서 최대로 차지할 수 있는 가변 길이 용량 크기이다.
- **독립 성장(Independent Growth)**: 스택이나 힙 영역이 타 영역을 침범하지 않고 상호 독립적인 방향으로 크기를 가변 확장하는 성질이다.

</details>

- 선택자와 오프셋이 결합된 **2차원 주소**를 사용하여 프로그램 논리 구조와 직접 매핑함.
- 기술자에 포함된 **기준 주소**와 **한계**를 대조하여 영역별 **독립 성장**과 경계를 하드웨어로 강력히 보호함.
- 다단계 테이블 탐색 없이 기준 주소에 오프셋을 더하는 단일 단계 변환을 수행함.

#### 한줄 요약

- 2차원 주소 체계를 사용하여 단순 덧셈 기반의 주소 변환을 수행하며 한계값 검사를 통한 영역 보호를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 기준 주소와 한계 크기, 유효 상태, 접근 권한 정보가 압축되어 저장된 구조체 데이터이다.
- **세그먼트 테이블(Segment Table)**: 시스템 전체 또는 개별 프로세스의 세그먼트 기술자 배열을 저장 보관하는 룩업 테이블이다.
- **서술자 특권 레벨(Descriptor Privilege Level)**: 해당 세그먼트에 접근하기 위해 요구되는 중앙처리장치의 최소 보안 등급을 의미하는 필드이다.

</details>

```text
[ 세그멘테이션 주소 변환 아키텍처 ]
+------------------------------------------+
| 가상 주소: [ 세그먼트 선택자 ] + [ 오프셋 ]    |
+------------------------------------------+
                  │                   │
                  ▼                   │
            [ 세그먼트 테이블 ]       │
            (기준 주소, 한계 반환)    │
                  │                   │
                  ▼                   ▼
            [ 권한 및 보호 한계 검사기 ]
                  │
                  ▼
            [ 물리 주소 덧셈 생성기 ]
                  │
                  ▼
            [ 물리 주소 공간 ]
```

| 구성요소 | 책임 |
|:---|:---|
| **세그먼트 기술자** | 논리 영역의 **기준 주소** 및 **한계**, 권한 정보 보관 유지 |
| 보호 검사기 | 한계 범위와 읽기/쓰기 등 특권 부여 조건 검사 수행 |
| 주소 생성기 | 유효 요청 시 기준 주소와 오프셋을 가산하여 물리 주소 계산 |
| **세그먼트 테이블** | 시스템 및 개별 프로세스의 전체 기술자 집합 보관 |

#### 한줄 요약

- 세그먼트 테이블과 보호 검사기, 주소 덧셈 연산기가 유기적으로 동작하여 논리 구조를 물리 공간으로 투영한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **세그먼트 번호(Segment Selector)**: 제어 레지스터에 탑재되어 기술자 테이블의 인덱스를 특정하는 선택 주소 필드이다.
- **보호 예외(Protection Exception)**: 오프셋이 한계를 초과하거나 권한이 없는 영역에 쓰기를 시도할 때 발생하는 하드웨어 예외 트랩이다.

</details>

```text
[ 메모리 접근 가상 주소 인가 ]
           │
           ▼
     [ 세그먼트 기술자 인출 ]
           │
           ▼
    [ 권한 및 존재 유효성 검사 ]
           │
     ┌─────┴─────┐
     ▼           ▼
[ 예외 발생 ] [ 검사 통과 ]
                 │
                 ▼
          [ 한계 오프셋 대조 검사 ]
                 │
           ┌─────┴─────┐
           ▼           ▼
      [ 보호 예외 ] [ 검사 통과 ]
                       │
                       ▼
             [ 물리 주소 덧셈 생성 ]
```

### 동작 원리

1. 기술자 인출: **세그먼트 번호**를 이용해 메모리 테이블에서 **세그먼트 기술자**를 인출함.
2. 권한 및 존재 검사: 해당 영역의 유효성과 읽기/쓰기 특권 레벨 등 접근 권한을 검증함.
3. 한계 검사: 오프셋이 설정된 물리적 한계를 초과하면 즉각 **보호 예외**를 발생시킴.
4. 물리 주소 생성: 모든 보호 검사를 통과하면 선형 덧셈 계산으로 실제 물리 주소를 도출함.

#### 한줄 요약

- 기술자를 인출하여 권한과 한계 경계를 철저히 검사한 후, 기준 주소와 오프셋을 더하여 안전한 주소를 도출한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **외부 단편화(External Fragmentation)**: 가변 크기 할당으로 메모리 빈 공간이 흩어져 전체 여유는 있으나 연속 구역이 부족해지는 현상이다.
- **세그먼트 페이징 혼용(Paged Segmentation)**: 세그멘테이션으로 논리 보호를 적용한 뒤, 내부를 고정 페이지 단위로 다시 쪼개어 적재하는 결합 아키텍처이다.

</details>

| 비교 항목 | 세그멘테이션 | 페이징 | 혼용 방식 (Paged Segmentation) |
|:---|:---|:---|:---|
| 분할의 기준 단위 | 프로그램의 논리 중심인 가변 크기 | 시스템 하드웨어 중심의 고정 크기 | 논리 세그먼트 내부를 페이지 단위 분할 |
| 주된 단편화 유형 | 파편화에 따른 심각한 **외부 단편화** | 고정 크기로 인한 국부적 내부 단편화 | 내부 단편화만 국소적으로 잔존 |
| 주소 변환 방식 | 기준에 오프셋을 더하는 단일 덧셈 기반 | 전용 테이블 탐색을 통한 매핑 기반 | 선택자 탐색 후 페이지 테이블 2중 매핑 |
| 메모리 배치 제약 | 반드시 연속된 묶음의 물리 공간 필요 | 비연속적인 개별 프레임 분산 배치 보장 | 비연속적인 물리 프레임 분산 배치 보장 |
| 구조적 장단점 | 논리적 모듈 보호와 공유에 탁월함 | 외부 파편화가 없어 메모리 할당 효율적 | 두 방식의 공유 보호 및 효율 장점 결합 |

#### 한줄 요약

- 세그멘테이션은 논리 보호에 강하지만 외부 단편화가 치명적이므로 현대 아키텍처에서는 두 기술을 혼용한 하이브리드 모델을 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 영역(Guard Page)**: 확장이 일어나는 스택 경계면에 접근을 통제하는 페이지를 두어 오버플로를 즉각 감지하는 기법이다.
- **TLB 지역성(TLB Locality)**: 다중 테이블을 거치는 혼용 환경에서 변환 지연을 차단하고자 캐시 버퍼 접근 효율을 극대화하는 최적화 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 크기 세그먼트 적재로 공간이 파편화되는 **외부 단편화** 누적 현상 | 고정 페이지 단위로 내부를 자르는 **세그먼트 페이징 혼용** 방식 도입 적용 | 외부 단편화 원천 제거 및 비연속 다중 적재 달성 |
| 스택의 동적 확장 시 타 데이터 영역을 무단 침범하는 치명적 메모리 오염 | 세그먼트 간의 경계면에 하드웨어 접근 불가 **가드 영역** 설정 적용 | 오버플로 발생 시 즉각적인 보호 예외 감지 및 방어 |
| 소프트웨어 개발자 오류로 설정된 한계 범위를 초과하는 악의적 접근 오작동 | 응용 모듈에 최소 권한 부여 및 컴파일러 기반 경계값 자동 시험 인가 | 하드웨어 트랩을 통한 메모리 침범 오작동 원천 차단 |
| 세그먼트와 페이지 다중 테이블 구조 조합에 따른 심각한 주소 변환 지연 발생 | 메모리 관리 장치 내부 **변환 색인 버퍼**의 보존 및 **TLB 지역성** 극대화 | 다중 테이블 탐색 지연을 단일 클록 사이클 속도로 은닉 |

#### 한줄 요약

- 혼용 기법으로 단편화를 제거하고 가드 영역과 고속 캐시 최적화를 통해 보안과 성능이라는 두 마리 토끼를 잡는다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **논리 보호 프레임워크(Logical Protection Framework)**: 물리적 페이징 기술을 밑바탕에 두고 응용 수준의 논리 권한 제어를 상부에 결합하는 최신 가상 메모리 설계 기준이다.

</details>

- 현대 시스템은 페이징을 주력으로 삼되 스택 보호 등에 세그먼트 경계 보호 개념을 선별적으로 융합함

#### 한줄 요약

- 외부 단편화의 한계를 페이징으로 회피하면서도 논리적 구조 보호라는 세그멘테이션의 핵심 철학을 실무에 결합해야 한다.
