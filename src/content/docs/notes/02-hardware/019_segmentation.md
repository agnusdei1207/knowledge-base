## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 코드·데이터·스택처럼 의미가 있는 가변 크기 단위로 나누는 메모리 관리 기법.
- **논리 주소(Logical Address)**: 세그먼트 식별자(선택자)와 세그먼트 내부 오프셋으로 표현한 프로그램 관점의 주소.
- **메모리 보호(Memory Protection)**: 세그먼트별 접근 권한과 한계로 허가되지 않은 메모리 사용을 막는 기능.

</details>

- 정의/개념: 코드·데이터·스택 같은 프로그램 논리 단위를 가변 크기 블록으로 나누고 각각의 시작 위치와 크기로 관리하는 **세그멘테이션**
- 배경/필요성: 고정 크기 분할은 영역마다 다른 크기와 권한을 표현하지 못해, 하드웨어가 **메모리 보호** 경계를 프로그램 의미와 맞출 수 없음

#### 한줄 요약
- 세그멘테이션이 겨눈 것은 메모리 활용률이 아니라 보호 경계를 프로그램의 의미와 일치시키는 일이며, 페이징이 끝내 흉내 내지 못한 부분도 이 지점이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기준 주소(Base)**: 세그먼트가 실제 물리 메모리에서 시작하는 선형 주소.
- **한계(Limit)**: 세그먼트 내부에서 허용하는 오프셋 최대 범위; 초과 시 보호 예외 발생.
- **외부 단편화(External Fragmentation)**: 빈 공간 총량은 충분하지만 연속된 큰 공간이 없어 가변 크기 세그먼트를 배치하지 못하는 현상.

</details>

- **기준 주소**와 **한계**를 대조해 세그먼트 범위를 벗어난 접근을 예외로 차단
- 세그먼트별 독립 성장과 공유로 논리 단위 경계의 유연한 관리
- 가변 크기 배치로 **외부 단편화** 발생; 연속 물리 공간 요구

#### 한줄 요약
- 크기를 자유롭게 정할 수 있다는 장점과 **외부 단편화**는 같은 성질의 앞뒷면이라, 하나만 취할 수 없다는 점이 이 방식의 구조적 한계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 기준 주소·한계·접근 권한·유효 상태를 기록한 세그먼트 테이블 항목.
- **세그먼트 테이블(Segment Table)**: 프로세스가 사용하는 세그먼트 기술자들을 모아 둔 테이블.
- **주소 생성기(Address Generator)**: 기준 주소에 오프셋을 더해 다음 단계 선형 주소를 만드는 회로.

</details>

```text
[세그멘테이션 변환 장치]
├─ 논리 주소
│  ├─ 세그먼트 선택자
│  └─ 오프셋
├─ 세그먼트 테이블
│  └─ 기술자 (Base·Limit·권한·유효 비트)
├─ 보호 검사기
└─ 주소 생성기
```

선의 의미: 가지(`├─`)는 변환 장치가 소유한 입력 필드·기술자 저장소·검사·주소 생성 책임

| 구성요소 | 책임 |
|:---|:---|
| 세그먼트 선택자 | 사용할 논리 영역 지정 |
| **세그먼트 테이블** | **세그먼트 기술자**를 통해 기준 주소·**한계**·권한 제공 |
| 보호 검사기 | 오프셋 범위와 접근 권한 판정·보호 예외 발생 |
| **주소 생성기** | **기준 주소**에 오프셋을 더해 다음 단계 주소 생성 |

#### 한줄 요약
- 검사와 주소 생성이 분리돼 있다는 점이 중요하며, 검사를 통과하지 못한 접근은 물리 주소 자체가 만들어지지 않아 잘못된 접근이 메모리에 닿을 경로가 없다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보호 예외(Protection Fault)**: 세그먼트 범위나 접근 권한을 위반했을 때 발생하는 동기 예외.
- **선형 주소(Linear Address)**: 세그먼트 변환 후 페이징 입력으로 사용되는 주소.

</details>

```text
논리 주소 입력 (선택자 | 오프셋)
      │
      ▼
1. 세그먼트 테이블 기술자 조회
      │
      ▼
2. 권한 및 한계 검사
      │
      ├─ 범위 초과·권한 오류 → 보호 예외 발생
      │
      └─ 통과 → 3. 선형 주소 생성 (Base + Offset)
```

분기 결과: 한계를 넘거나 권한이 맞지 않으면 **보호 예외**로 즉시 중단되고, 통과한 경우에만 **선형 주소**가 생성되어 다음 변환 단계로 전달

#### 한줄 요약
- 모든 접근마다 기술자를 조회해야 하므로 보호의 정밀도는 높지만 변환 지연이 접근마다 붙으며, 이 상시 비용이 세그멘테이션 퇴장의 실질적 이유였다.

## Ⅴ. 종류 및 비교

| 메모리 분할 방식 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 적용 기준 | 논리 단위 보호·공유 경계 우선 | 고정 단위·비연속 배치 우선 |
| 핵심 특징 | 가변 세그먼트를 기준 주소와 한계로 보호 | 고정 크기 페이지·프레임의 비연속 배치 |
| 한계 | **외부 단편화**와 가변 할당 관리 복잡도 | 내부 단편화와 페이지 테이블 메모리 비용 |

#### 한줄 요약
- 두 방식은 배타적 선택지가 아니었고 실제 역사는 페이징이 배치를 맡고 세그멘테이션의 보호 개념만 페이지 권한 비트로 흡수되는 쪽으로 정리됐다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 페이지(Guard Page)**: 접근 불가 페이지를 세그먼트 경계에 배치해 스택 오버플로를 예외로 조기 감지하는 기법.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 주소 변환 결과를 캐싱해 반복 변환 지연을 줄이는 캐시.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 배치·해제 반복으로 **외부 단편화** 증가 | 페이징 결합·비연속 프레임 배치 | 큰 연속 공간 의존 완화 |
| 스택 확장이 인접 세그먼트 침범 | **가드 페이지**·세그먼트 권한 설정 | 오버플로 조기 감지 |
| 세그먼트 권한 설정 오류 | 코드·데이터·스택 권한 분리 검증 | 비허가 접근 차단 |
| 기술자 조회가 반복 변환 지연 유발 | **TLB**에 변환 결과 캐싱 | 반복 변환 지연 감소 |

#### 한줄 요약
- 네 대책 중 셋이 페이징과 **TLB**를 끌어오는 데서 보이듯, 세그멘테이션의 약점은 대부분 세그멘테이션 안에서는 해결되지 않는다.

## Ⅶ. 결론

- 현대 범용 64비트 시스템은 페이징과 페이지 권한을 기본으로 유지하고, **세그멘테이션**은 논리 영역을 하드웨어 경계로 분리해야 하는 호환·특수 환경에 한정

#### 한줄 요약
- 세그멘테이션이 남긴 유산은 구현이 아니라 개념이며, 오늘날 페이지 단위 권한 비트가 그 개념을 훨씬 싼 비용으로 수행하고 있다.
