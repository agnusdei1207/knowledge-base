## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 프로그램의 가상 주소 공간을 코드(Code), 데이터(Data), 스택(Stack), 힙(Heap) 등 논리적 기능 단위(가변 크기)로 분할하여 매핑하고 보호하는 메모리 관리 기법.
- **논리 주소(Logical Address)**: 세그먼트 선택자(Segment Selector)와 세그먼트 내 변위 오프셋(Offset)으로 구성된 2차원 가상 주소.
- **메모리 보호(Memory Protection)**: 세그먼트 기술자에 정의된 접근 권한(R/W/X), 한계(Limit) 및 특권 레벨(DPL)을 하드웨어적으로 대조하여 불법 접근을 차단하는 기법.

</details>

- 정의/개념: 프로그램 논리 구조에 맞추어 가변 크기의 세그먼트로 메모리를 분할하고 **기준 주소**(Base)와 **한계**(Limit)로 변환 및 보호를 수행하는 메모리 관리 기법
- 배경/필요성: 고정 크기 페이징만으로는 프로그램의 **논리 모듈별 권한 격리** 및 코드 공유 한계 발생

#### 한줄 요약
- 세그멘테이션은 프로그램의 논리적 의미 단위로 메모리를 분할하여 보호와 공유를 직관적으로 구현하는 2차원 주소 관리 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기준 주소(Base Address)**: 세그먼트가 물리 메모리(또는 선형 주소 공간) 상에서 시작하는 기준 시작 위치.
- **세그먼트 한계(Segment Limit)**: 세그먼트의 유효 물리적 크기 범위를 정의하는 값으로, 오프셋이 한계를 초과하면 하드웨어 보호 예외(General Protection Fault) 발생.
- **외부 단편화(External Fragmentation)**: 가변 크기 세그먼트들의 동적 할당과 해제가 반복되어 총 유휴 공간은 충분하나 연속된 블록이 없어 새 세그먼트를 적재하지 못하는 현상.

</details>

- 세그먼트별 **기준 주소**(Base)와 **한계**(Limit) 및 R/W/X 권한 독립 부여를 통한 침범 차단
- 코드 세그먼트의 읽기 전용 공유 설정을 통한 **공유 라이브러리** 지원
- 가변 크기 할당 및 해제 반복에 따른 **외부 단편화**(External Fragmentation) 발생

#### 한줄 요약
- 세그멘테이션은 논리적 모듈 보호와 공유에 유리하지만, 가변 크기 할당으로 인한 외부 단편화가 구조적 한계이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 Base(32비트), Limit(20비트), DPL(특권 레벨), R/W/X 권한 비트를 정의하는 8바이트 하드웨어 디스크립터.
- **세그먼트 테이블(Segment Table / GDT·LDT)**: 프로세스가 참조할 수 있는 세그먼트 기술자들의 배열을 저장하는 하드웨어 디스크립터 테이블.
- **세그먼트 레지스터(Segment Register)**: CPU 내부에서 현재 실행 중인 CS(코드), DS(데이터), SS(스택) 세그먼트 선택자를 보관하는 16비트 레지스터.

</details>

```text
세그멘테이션 서브시스템 (Segmentation Subsystem)
 ├─ CPU 코어 (세그먼트 레지스터: CS, DS, SS, ES)
 ├─ 메모리 관리 장치 (MMU)
 │   ├─ 디스크립터 참조 레지스터 (GDTR / LDTR)
 │   ├─ 한계 및 접근 권한 검사기
 │   └─ 선형 주소 도출 가산기 (Base + Offset)
 └─ 메인 메모리 (DRAM)
     └─ 세그먼트 디스크립터 테이블 (GDT / LDT)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 레지스터 및 변환 모듈의 계층 포함 관계

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| 세그먼트 레지스터 | CPU 내부 레지스터 | CS, DS, SS 등 활성 **세그먼트 선택자** 보관 | 16비트 하드웨어 레지스터 |
| 세그먼트 테이블 | DRAM (GDT/LDT) | 모든 세그먼트의 **기술자**(Base, Limit, 권한) 보관 | OS 커널이 생성 및 관리 |
| 권한 검사기 | MMU 세그먼트 회로 | 오프셋의 **한계 초과** 및 접근 권한(R/W/X) 위반 검증 | 위반 시 #GP 트랩 발생 |
| 주소 가산기 | MMU 세그먼트 회로 | Base 주소에 Offset을 가산하여 **선형 주소** 도출 | 1클록 하드웨어 가산 |

#### 한줄 요약
- 세그멘테이션 유닛은 세그먼트 레지스터로 기술자를 찾아 한계와 권한을 검사한 뒤, Base와 Offset을 더해 선형 주소를 만든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **일반 보호 예외(General Protection Fault, #GP)**: 세그먼트 한계를 초과하거나 권한이 없는 영역에 쓰기를 시도할 때 CPU가 발행하는 동기적 트랩 예외.
- **선형 주소(Linear Address)**: 세그멘테이션 변환(Base + Offset)의 결과 주소로, 페이징 유닛의 입력 주소로 사용됨.

</details>

```text
CPU 논리 주소 (Segment Selector : Offset) 발행
       │
       ▼
1. 세그먼트 테이블(GDT/LDT)에서 세그먼트 기술자(Descriptor) 인출
       │
       ▼
2. 한계(Limit) 및 접근 권한(R/W/X) 하드웨어 검증
       │
       ├─ 한계 초과·권한 불일치 ──► 일반 보호 예외(#GP Fault) 발생 및 프로세스 종료
       │
       └─ 검증 통과 (정상 접근)
              │
              ▼
       3. 주소 가산기: 선형 주소(Base + Offset) 도출
              │
              ▼
       4. 페이징 유닛으로 선형 주소 전달 및 물리 메모리 접근
```

분기 결과: **범위나 권한 위반** 시 #GP 하드웨어 트랩 즉시 발생, **정상 검증 통과** 시 Base+Offset 선형 주소 계산 후 페이징 유닛 전송

#### 한줄 요약
- 논리 주소 접근 시 기술자의 한계와 권한을 하드웨어로 대조하여 위반 시 #GP 예외를 발생시키고, 통과 시 Base+Offset으로 선형 주소를 계산한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 세그멘테이션 (Segmentation) | 페이징 (Paging) |
|:---|:---|:---|
| 분할 기준 | **논리적 가변 단위**(함수, 배열, 스택) | **고정 크기 블록**(4KB, 2MB) |
| 주소 체계 | 2차원 주소 (세그먼트 번호 + 오프셋) | 1차원 주소 (가상 페이지 번호 + 오프셋) |
| 단편화 현상 | **외부 단편화** 발생 (메모리 압축 필요) | **내부 단편화** 발생 (외부 단편화 0%) |
| 주소 변환 하드웨어 | 세그먼트 테이블 (Base/Limit 비교기) | **다단계 페이지 테이블** 및 TLB |
| 현대 시스템 위상 | 64비트 x86_64에서 **Flat 모드** 비활성화 | 현대 범용 OS의 **표준 메모리 관리** |

#### 한줄 요약
- 세그멘테이션은 논리적 모듈 관리에 특화되었으나 외부 단편화로 인해 퇴장하였고, 현대 시스템은 페이징이 메모리 관리의 중심이 되었다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **플랫 메모리 모델(Flat Memory Model)**: 모든 세그먼트의 Base를 0으로, Limit을 최대 주소 공간으로 고정하여 세그멘테이션 변환을 사실상 무력화하고 단일 선형 주소 공간으로 취급하는 기법.
- **가드 페이지(Guard Page)**: 스택 세그먼트 경계에 할당된 무접근 특수 페이지로, 스택 오버플로 시 즉시 페이지 폴트를 유발하여 인접 영역 침범을 방지하는 기법.

</details>

| 문제 상황 | 대응 전략 | 기대 효과 |
|:---|:---|:---|
| 가변 세그먼트 할당에 따른 **외부 단편화** 발생 | **플랫 메모리 모델**(Flat Model) 적용 후 페이징 일원화 | 외부 단편화 100% 제거 및 비연속 프레임 할당 |
| 스택 영역 확장에 따른 인접 영역 침범 위험 | 스택 하단에 **가드 페이지**(Guard Page) 배치 | 버퍼 오버플로 침범 조기 감지 및 메모리 보호 |
| 세그먼트 변환 및 기술자 조회에 따른 변환 지연 | **TLB** 내 선형-물리 주소 변환 결과 일괄 캐싱 | 주소 변환 오버헤드 1클록 내 단축 |

#### 한줄 요약
- 실무에서는 플랫 메모리 모델로 세그멘테이션을 우회하고 페이징으로 일원화하며, 스택 침범은 가드 페이지로 방어한다.

## Ⅶ. 결론

- 단편화 방지와 모듈 보호를 위한 **플랫 모델** 및 **PTE 속성 비트** 통합 체계 확립

#### 한줄 요약
- 세그멘테이션의 물리 변환은 퇴장했으나, 모듈별 권한 보호 개념은 현대 페이징의 속성 비트로 승계되어 완성되었다.
