## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 의미론적 성격이 같은 논리적 단위인 가변 크기의 세그먼트(Code, Data, Stack)로 나누어 관리하는 기법.
- **논리 권한 경계(Logical Permission Boundary)**: 코드(R-X), 데이터(R-W), 스택(R-W) 등 논리 구역별로 부여된 특화된 메모리 접근 제어 한계선.
- **평면 주소 공간(Flat Address Space)**: 논리 구분 없이 시작부터 끝 번지까지를 하나의 단일 연속 메모리로 취급하는 구조.

</details>

- 정의/개념: 가상 주소 공간을 의미론적 성격이 같은 논리적 단위인 가변 크기의 세그먼트(Code, Data, Stack)로 분할하여 주소 변환과 보호를 수행하는 메모리 관리 기법
- 배경/필요성: 평면 메모리 구조의 코드/데이터 침범을 방지하고 **논리적 모듈 단위의 접근 권한 제어 및 코드 공유 메커니즘 제공**

#### 한줄 요약

- 가상 메모리를 논리 모듈 단위로 분할하여 **독립된 Base/Limit 기반 주소 변환 및 보호** 제공

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **2차원 주소(Two-Dimensional Address)**: 세그먼트 선택자(Selector)와 오프셋(Offset) 2개의 매개변수로 구성된 주소 체계.
- **Base / Limit**: 세그먼트가 시작되는 물리 메모리 시작 번지(Base)와 해당 세그먼트의 최대 허용 크기(Limit).

</details>

- 세그먼트 선택자와 오프셋이 결합된 **2차원 주소**를 통한 프로그램 논리 구조와의 직접 매핑
- 기술자에 포함된 **기준 주소(Base)**와 **한계(Limit)** 대조를 통한 영역별 **독립 성장** 및 하드웨어 경계 보호
- 다단계 테이블 탐색 대신 $\text{Physical Address} = \text{Base} + \text{Offset}$ 단일 덧셈 주소 변환 수행

#### 한줄 요약

- 2차원 주소 체계와 **Base + Offset 덧셈 연산 및 Limit 경계 검사** 수행

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 Base, Limit, DPL(권한 레벨), Valid 비트를 담은 8바이트 구조체.
- **GDT / LDT**: 전역 세그먼트 기술자 테이블(Global Descriptor Table)과 프로세스별 로컬 기술자 테이블(Local Descriptor Table).

</details>

```text
[ 세그멘테이션 주소 변환 아키텍처 ]
+-----------------------------------------------------------+
| 가상 주소 (Logical Address) : [ 세그먼트 선택자 ] + [ 오프셋 ] |
+-----------------------------------------------------------+
                  │                                   │
                  ▼                                   │
      [ 세그먼트 테이블 (GDT / LDT) ]                 │
      (Base Address, Limit, 권한 반환)                │
                  │                                   │
                  ▼                                   ▼
      [ 권한 검사 및 Limit 경계 검사기 ] ──(초과 시 Protection Fault)
                  │
                  ▼ (통과 시)
      [ 물리 주소 덧셈 생성기 (Base + Offset) ]
                  │
                  ▼
      [ 물리 메모리 공간 (DRAM) ]
```

선의 의미: 가상 주소(Segment Selector + Offset)로부터 세그먼트 기술자 참조, Limit 검사 및 Base 가산을 통한 물리 주소 생성 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 세그먼트 기술자 | 논리 영역의 **기준 주소(Base)** 및 **한계(Limit)**, 권한 정보 보관 |
| 보호 검사기 | Limit 범위 초과 여부 및 R/W/X 특권 레벨 검사 수행 |
| 주소 생성기 | 유효 요청 시 기준 주소(Base)에 오프셋을 가산하여 물리 주소 생성 |
| 세그먼트 테이블 | 시스템(GDT) 및 프로세스(LDT)의 전체 기술자 배열 보관 |

#### 한줄 요약

- **세그먼트 기술자(Base/Limit/권한)와 하드웨어 한계 검사기**의 유기적 연동

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **General Protection Fault(#GP)**: 세그먼트 크기(Limit)를 초과하거나 권한이 없는 영역에 쓰기를 시도할 때 CPU가 발생시키는 하드웨어 예외.

</details>

```text
[ 가상 메모리 접근 요청 (Selector + Offset) ]
                      │
                      ▼
         [ 세그먼트 기술자 인출 (Descriptor) ]
                      │
                      ▼
         [ 유효성 및 DPL 권한 레벨 검사 ]
                      │
            ┌─────────┴─────────┐
            ▼ [권한 불일치]     ▼ [통과]
      [ #GP 예외 발생 ]   [ Offset <= Limit 한계 검사 ]
                                │
                      ┌─────────┴─────────┐
                      ▼ [초과]            ▼ [통과]
                [ #GP 예외 발생 ]   [ 물리 주소 생성 (Base + Offset) ]
```

**동작 원리**

1. **기술자 인출**: 세그먼트 선택자로 GDT/LDT를 인덱싱하여 해당 세그먼트 기술자 인출
2. **권한 검사**: CPU의 현재 특권 레벨(CPL)과 세그먼트 기술자의 권한(DPL) 대조 검증
3. **한계 검사**: 오프셋이 설정된 세그먼트 크기(Limit) 이내인지 하드웨어 비교기 검사
4. **물리 주소 생성**: 모든 검사를 통과하면 Base 주소에 Offset을 더하여 실제 물리 주소 도출

#### 한줄 요약

- **기술자 인출 $\to$ 권한/Limit 검증 $\to$ Base + Offset 가산**을 통한 안전한 주소 생성

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **외부 단편화(External Fragmentation)**: 가변 크기 메모리 할당/해제가 반복되면서 남은 여유 공간의 총합은 충분하나 연속된 블록이 없어 적재하지 못하는 현상.

</details>

| 메모리 분할 기법 | 세그멘테이션 (Segmentation) | 페이징 (Paging) | 세그먼트 페이징 혼용 (Paged Segmentation) |
|:---|:---|:---|:---|
| 적용 기준 | 모듈별 보호 및 공유가 강조되는 논리 단위 분할 | 현대 64비트 범용 운영체제 및 가상 메모리 표준 | 논리적 모듈 보호와 물리적 프레임 할당 편의 동시 요구 시 |
| 핵심 특징 | 가변 크기 세그먼트, Base + Offset 덧셈 주소 변환 | 고정 크기(4KB) 페이지, 페이지 테이블 매핑 주소 변환 | 세그먼트 내부를 고정 크기 페이지로 2차 분할 매핑 |
| 한계 및 위험 | 가변 크기 적재로 인한 심각한 외부 단편화(External) | 페이지 내부 낭비인 국소적 내부 단편화(Internal) | 2단계 주소 변환에 따른 메모리 참조 지연 오버헤드 |

#### 한줄 요약

- 세그멘테이션은 **논리 보호와 외부 단편화**, 페이징은 **관리 용이성과 내부 단편화**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 페이지(Guard Page)**: 스택 세그먼트의 끝부분에 의도적으로 접근 불가능한 페이지를 배치하여 스택 오버플로를 즉각 감지하고 방어하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 크기 세그먼트 적재로 공간이 파편화되는 **외부 단편화** 누적 현상 | 고정 페이지 단위로 내부를 자르는 **세그먼트 페이징 혼용** 방식 도입 적용 | 외부 단편화 원천 제거 및 비연속 다중 적재 달성 |
| 스택의 동적 확장 시 타 데이터 영역을 무단 침범하는 치명적 메모리 오염 | 세그먼트 간의 경계면에 하드웨어 접근 불가 **가드 영역** 설정 적용 | 오버플로 발생 시 즉각적인 보호 예외 감지 및 방어 |
| 소프트웨어 개발자 오류로 설정된 한계 범위를 초과하는 악의적 접근 오작동 | 응용 모듈에 최소 권한 부여 및 컴파일러 기반 경계값 자동 시험 인가 | 하드웨어 트랩을 통한 메모리 침범 오작동 원천 차단 |
| 세그먼트와 페이지 다중 테이블 구조 조합에 따른 심각한 주소 변환 지연 발생 | 메모리 관리 장치 내부 **변환 색인 버퍼**의 보존 및 **TLB 지역성** 극대화 | 다중 테이블 탐색 지연을 단일 클록 사이클 속도로 은닉 |

#### 한줄 요약

- **Paged Segmentation 혼용·가드 페이지(Guard Page)·TLB 가속**으로 단점 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **VMA(Virtual Memory Area)**: 리눅스 커널 등 현대 OS가 하드웨어 세그멘테이션 대신 소프트웨어 레벨에서 코드, 데이터, 힙, 스택 구역을 구조체로 관리하는 체계.

</details>

- 64비트 아키텍처는 **Flat Memory Model 기반 페이징을 표준으로 삼되, 논리적 보호는 가상 메모리 영역(VMA) 구조체로 구현**

#### 한줄 요약

- **페이징 기반 물리 관리 위에 세그멘테이션의 논리적 보호 철학**을 결합
