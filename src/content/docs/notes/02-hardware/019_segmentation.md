## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 코드, 데이터, 스택, 힙 등 프로그램의 논리적 모듈 단위(가변 크기)로 분할하여 매핑하고 보호하는 메모리 관리 기법.
- **논리 주소(Logical Address)**: 세그먼트 선택자(Segment Selector)와 세그먼트 내 오프셋(Offset)으로 구성된 2차원 형태의 프로그램 관점 주소.
- **메모리 보호(Memory Protection)**: 세그먼트 기술자에 정의된 접근 권한(R/W/X), 세그먼트 한계(Limit) 및 특권 레벨(DPL)을 하드웨어적으로 대조하여 불법적인 메모리 접근을 차단하는 기법.

</details>

- 정의/개념: 코드·데이터·스택 같은 프로그램 논리 단위를 가변 크기 블록으로 나누고 각각의 시작 위치와 크기로 관리하는 **세그멘테이션**
- 배경/필요성: 고정 크기 분할은 영역마다 다른 크기와 권한을 표현하지 못해, 하드웨어가 **메모리 보호** 경계를 프로그램 의미와 맞출 수 없음

#### 한줄 요약
- 세그멘테이션이 겨눈 것은 메모리 활용률이 아니라 보호 경계를 프로그램의 의미와 일치시키는 일이며, 페이징이 끝내 흉내 내지 못한 부분도 이 지점이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기준 주소(Base)**: 세그먼트가 물리 메모리(또는 선형 주소 공간) 상에서 시작하는 기준 시작 물리 주소.
- **한계(Limit)**: 세그먼트의 유효 물리적 크기 범위를 정의하는 값으로, 오프셋이 한계를 초과할 경우 하드웨어 보호 예외(General Protection Fault)를 발생시킴.
- **외부 단편화(External Fragmentation)**: 가변 크기 세그먼트들의 동적 할당 및 해제가 반복됨에 따라 전체 여유 메모리 공간은 충분하나 연속된 유휴 블록이 없어 새 세그먼트를 할당하지 못하는 현상.

</details>

- **기준 주소** 및 **한계** 활용 대조해 세그먼트 범위를 벗어난 접근을 예외로 차단
- 세그먼트별 독립 성장과 공유로 논리 단위 경계의 유연한 관리
- 가변 크기 배치로 **외부 단편화** 발생; 연속 물리 공간 요구

#### 한줄 요약
- 크기를 자유롭게 정할 수 있다는 장점과 **외부 단편화** 기반 같은 성질의 앞뒷면이라, 하나만 취할 수 없다는 점이 이 방식의 구조적 한계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 세그먼트의 기준 시작 주소(Base), 크기 한계(Limit), 접근 권한(R/W/X), 유효 상태 및 특권 레벨 정보를 포함하는 8바이트 디스크립터 구조체.
- **세그먼트 테이블(Segment Table)**: 프로세스가 참조할 수 있는 모든 세그먼트 기술자들을 저장 및 관리하는 하드웨어 디스크립터 테이블(GDT/LDT).
- **주소 생성기(Address Generator)**: 세그먼트 기술자로부터 인출한 기준 주소(Base)에 논리 주소의 오프셋(Offset)을 덧셈 연산하여 유효 선형 주소를 계산하는 전용 가산기 회로.

</details>

```text
[세그멘테이션 변환 장치]
├─ 논리 주소
│  ├─ 세그먼트 선택자
│  └─ 오프셋
├─ 세그먼트 테이블
│  └─ 기술자 (Base·Limit·권한·유효 비트)
├─ 보호 검사기
└─ 주소 생성기
```

선의 의미: 가지(`├─`)는 변환 장치가 소유한 입력 필드·기술자 저장소·검사·주소 생성 책임

| 구성요소 | 책임 |
|:---|:---|
| 세그먼트 선택자 | 사용할 논리 영역 지정 |
| **세그먼트 테이블** | **세그먼트 기술자** 활용 통해 기준 주소·**한계**·권한 제공 |
| 보호 검사기 | 오프셋 범위와 접근 권한 판정·보호 예외 발생 |
| **주소 생성기** | **기준 주소** 대상 오프셋을 더해 다음 단계 주소 생성 |

#### 한줄 요약
- 검사와 주소 생성이 분리돼 있다는 점이 중요하며, 검사를 통과하지 못한 접근은 물리 주소 자체가 만들어지지 않아 잘못된 접근이 메모리에 닿을 경로가 없다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보호 예외(Protection Fault)**: 세그먼트 한계 초과, 권한 불일치(읽기 전용 세그먼트에 쓰기 시도 등) 발생 시 CPU가 발행하는 동기적 하드웨어 트랩 예외.
- **선형 주소(Linear Address)**: 세그멘테이션 변환(Base + Offset)을 거쳐 생성된 주소로, 페이징 활성화 시 페이징 유닛의 입력 가상 주소로 사용되는 1차원 주소.

</details>

```text
논리 주소 입력 (선택자 | 오프셋)
      │
      ▼
1. 세그먼트 테이블 기술자 조회
      │
      ▼
2. 권한 및 한계 검사
      │
      ├─ 범위 초과·권한 오류 → 보호 예외 발생
      │
      └─ 통과 → 3. 선형 주소 생성 (Base + Offset)
```

분기 결과: 한계를 넘거나 권한이 맞지 않으면 **보호 예외** 기반 즉시 중단되고, 통과한 경우에만 **선형 주소** 생성되어 다음 변환 단계로 전달

#### 한줄 요약
- 모든 접근마다 기술자를 조회해야 하므로 보호의 정밀도는 높지만 변환 지연이 접근마다 붙으며, 이 상시 비용이 세그멘테이션 퇴장의 실질적 이유였다.

## Ⅴ. 종류 및 비교

| 메모리 분할 방식 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 적용 기준 | 논리 단위 보호·공유 경계 우선 | 고정 단위·비연속 배치 우선 |
| 핵심 특징 | 가변 세그먼트를 기준 주소와 한계로 보호 | 고정 크기 페이지·프레임의 비연속 배치 |
| 한계 | **외부 단편화** 및 가변 할당 관리 복잡도 | 내부 단편화와 페이지 테이블 메모리 비용 |

#### 한줄 요약
- 두 방식은 배타적 선택지가 아니었고 실제 역사는 페이징이 배치를 맡고 세그멘테이션의 보호 개념만 페이지 권한 비트로 흡수되는 쪽으로 정리됐다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 페이지(Guard Page)**: 세그먼트 경계 또는 스택 영역 하단에 할당된 접근 불가(No-Access) 특수 페이지로, 스택 오버플로 시 즉시 페이지 폴트 예외를 유발하여 인접 세그먼트 침범을 조기에 차단하는 기법.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 세그멘테이션 및 페이징 변환 결과를 캐싱하여 주소 변환에 소요되는 테이블 조회 지연을 최소화하는 고속 주소 변환 캐시.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 배치·해제 반복으로 **외부 단편화** 증가 | 페이징 결합·비연속 프레임 배치 | 큰 연속 공간 의존 완화 |
| 스택 확장이 인접 세그먼트 침범 | **가드 페이지**·세그먼트 권한 설정 | 오버플로 조기 감지 |
| 세그먼트 권한 설정 오류 | 코드·데이터·스택 권한 분리 검증 | 비허가 접근 차단 |
| 기술자 조회가 반복 변환 지연 유발 | **TLB** 대상 변환 결과 캐싱 | 반복 변환 지연 감소 |

#### 한줄 요약
- 네 대책 중 셋이 페이징과 **TLB** 활용 끌어오는 데서 보이듯, 세그멘테이션의 약점은 대부분 세그멘테이션 안에서는 해결되지 않는다.

## Ⅶ. 결론

- 현대 범용 64비트 시스템은 페이징과 페이지 권한을 기본으로 유지하고, **세그멘테이션** 논리 영역을 하드웨어 경계로 분리해야 하는 호환·특수 환경에 한정

#### 한줄 요약
- 세그멘테이션이 남긴 유산은 구현이 아니라 개념이며, 오늘날 페이지 단위 권한 비트가 그 개념을 훨씬 싼 비용으로 수행하고 있다.
