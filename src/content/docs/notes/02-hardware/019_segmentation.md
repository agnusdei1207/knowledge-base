## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **세그멘테이션(Segmentation)**: 가상 주소 공간을 코드·데이터·스택처럼 의미가 있는 가변 크기 단위로 나누는 메모리 관리 기법.
- **논리 주소(Logical Address)**: 세그먼트 식별자(선택자)와 세그먼트 내부 오프셋으로 표현한 프로그램 관점의 주소.
- **메모리 보호(Memory Protection)**: 세그먼트별 접근 권한과 한계로 허가되지 않은 메모리 사용을 막는 기능.

</details>

- 정의/개념: 코드·데이터·스택 등 프로그램 논리 단위를 가변 크기 블록으로 분할하여 **기준 주소와 한계(Limit)** 로 관리하는 메모리 기법
- 배경/필요성: 고정 크기 분할만으로는 코드·데이터·스택의 서로 다른 크기와 **보호·공유 경계** 표현 제약

#### 한줄 요약
- 프로그램의 의미 단위마다 시작점과 크기를 따로 기록해 각 영역을 독립적으로 보호하고 배치하는 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기준 주소(Base)**: 세그먼트가 실제 물리 메모리에서 시작하는 선형 주소.
- **한계(Limit)**: 세그먼트 내부에서 허용하는 오프셋 최대 범위; 초과 시 보호 예외 발생.
- **외부 단편화(External Fragmentation)**: 빈 공간 총량은 충분하지만 연속된 큰 공간이 없어 가변 크기 세그먼트를 배치하지 못하는 현상.

</details>

- **기준 주소**와 **한계 검사**로 세그먼트 범위를 벗어난 접근을 보호 예외로 차단
- 세그먼트별 독립 성장과 공유로 논리 단위 경계의 유연한 관리
- 가변 크기 배치로 **외부 단편화** 발생; 연속 물리 공간 요구

#### 한줄 요약
- 필요한 크기만 영역으로 만들 수 있는 대신, 영역을 자주 만들고 없애면 메모리 사이에 작은 빈틈이 남아 새 세그먼트를 넣지 못한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세그먼트 기술자(Segment Descriptor)**: 기준 주소·한계·접근 권한·유효 상태를 기록한 세그먼트 테이블 항목.
- **세그먼트 테이블(Segment Table)**: 프로세스가 사용하는 세그먼트 기술자들을 모아 둔 테이블.
- **주소 생성기(Address Generator)**: 기준 주소에 오프셋을 더해 다음 단계 선형 주소를 만드는 회로.

</details>

```text
[세그멘테이션 변환 장치]
├─ 논리 주소
│  ├─ 세그먼트 선택자
│  └─ 오프셋
├─ 세그먼트 테이블
│  └─ 기술자 (Base·Limit·권한·유효 비트)
├─ 보호 검사기
└─ 주소 생성기
```

선의 의미: 가지(`├─`)는 변환 장치가 소유한 입력 필드·기술자 저장소·검사·주소 생성 책임

| 구성요소 | 책임 |
|:---|:---|
| 세그먼트 선택자 | 사용할 논리 영역 지정 |
| 세그먼트 테이블 | 기준 주소·**한계**·권한 정보 제공 |
| 보호 검사기 | 오프셋 범위와 접근 권한 판정·보호 예외 발생 |
| 주소 생성기 | Base + Offset으로 **선형 주소** 생성 |

#### 한줄 요약
- 선택자로 영역을 고르고 기술자에서 기준·크기·권한을 읽은 뒤, 검사기를 통과한 오프셋만 선형 주소로 변환한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보호 예외(Protection Fault)**: 세그먼트 범위나 접근 권한을 위반했을 때 발생하는 동기 예외.
- **선형 주소(Linear Address)**: 세그먼트 변환 후 페이징 입력으로 사용되는 주소.

</details>

```text
논리 주소 입력 (선택자 | 오프셋)
      │
      ▼
1. 세그먼트 테이블 기술자 조회
      │
      ▼
2. 권한 및 한계 검사
      │
      ├─ 범위 초과·권한 오류 → 보호 예외 발생
      │
      └─ 통과 → 3. 선형 주소 생성 (Base + Offset)
```

**동작 원리**

1. **세그먼트 테이블 기술자 조회**: 선택자 인덱스로 Base·Limit·권한 조회
2. **권한 및 한계 검사**: 오프셋 범위 및 읽기·쓰기·실행 권한 일치 확인
3. **선형 주소 생성**: 검사 통과 후 Base + Offset으로 선형 주소 계산

#### 한줄 요약
- 영역의 이름을 찾고 접근 권한과 범위를 확인한 뒤에만 그 영역 안의 실제 선형 주소를 계산한다.

## Ⅴ. 종류 및 비교

| 메모리 분할 방식 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 적용 기준 | 논리 단위 보호·공유 경계 우선 | 고정 단위·비연속 배치 우선 |
| 핵심 특징 | 가변 세그먼트·Base+Limit 보호 | 고정 페이지·프레임 비연속 **매핑** |
| 한계 | **외부 단편화**·가변 할당 관리 복잡 | **내부 단편화**·페이지 테이블 메모리 비용 |

#### 한줄 요약
- 세그멘테이션은 프로그램 의미 단위 보호에 강하고, 페이징은 물리 메모리 비연속 배치 관리에 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가드 페이지(Guard Page)**: 접근 불가 페이지를 세그먼트 경계에 배치해 스택 오버플로를 예외로 조기 감지하는 기법.
- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 주소 변환 결과를 캐싱해 반복 변환 지연을 줄이는 캐시.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 배치·해제 반복으로 **외부 단편화** 증가 | 페이징 결합·비연속 프레임 배치 | 큰 연속 공간 의존 완화 |
| 스택 확장이 인접 세그먼트 침범 | **가드 페이지**·세그먼트 권한 설정 | 오버플로 조기 감지 |
| 세그먼트 권한 설정 오류 | 코드·데이터·스택 권한 분리 검증 | 비허가 접근 차단 |
| 기술자 조회가 반복 변환 지연 유발 | **TLB**에 변환 결과 캐싱 | 반복 변환 지연 감소 |

#### 한줄 요약
- 현대 시스템은 세그먼트의 논리 보호 장점을 남기면서, 페이징과 TLB로 외부 단편화와 변환 비용을 보완한다.

## Ⅶ. 결론

- 현대 범용 64비트 시스템은 **페이징**과 페이지 권한을 기본으로 유지하고, **세그멘테이션**은 논리 영역을 하드웨어 경계로 분리해야 하는 호환·특수 환경에 한정

#### 한줄 요약
- 세그멘테이션은 논리 보호가 필요한 곳에 의미 있고, 범용 시스템은 관리 비용이 낮은 페이징을 기본으로 세그멘테이션을 보조로 사용한다.
