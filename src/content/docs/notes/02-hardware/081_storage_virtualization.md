## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스토리지 가상화(Storage Virtualization)**: 다수의 물리적 저장장치(HDD, SSD, SAN 어레이)를 논리적으로 통합 및 추상화하여 호스트 서버에 독립된 가상 스토리지 풀로 제공하는 기술.
- **논리-물리 주소 매핑(LBA Mapping)**: 호스트가 바라보는 가상 블록 주소와 실제 물리 디스크의 블록 주소를 실시간으로 변환하는 추상화 계층.

</details>

- 정의/개념: 이기종 물리 스토리지를 추상화하여 단일 스토리지 풀과 가상 볼륨(Virtual LUN)으로 제공하는 **스토리지 가상화**
- 배경/필요성: 벤더별 스토리지 사일로화로 인해 **용량 불균형 해소 및 무중단 온라인 데이터 이관 불가**

#### 한줄 요약
- 물리 스토리지의 복잡성을 은닉하고 논리-물리 매핑을 통해 동적 용량 관리와 무중단 마이그레이션을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **씬 프로비저닝(Thin Provisioning)**: 호스트에는 대용량 가상 볼륨을 미리 할당하고 실제 물리 디스크 공간은 데이터가 쓰이는 시점에 동적으로 할당하는 기술.
- **온라인 마이그레이션(Online Migration)**: 서비스 중단 없이 백그라운드에서 데이터를 구형 스토리지에서 신형 스토리지로 실시간 이관하는 기능.

</details>

- 호스트와 물리 디스크 간의 결합도를 제거하는 **논리-물리 주소 매핑 분리**
- 실제 쓰기 시점에만 물리 블록을 떼어주는 **씬 프로비저닝** 기반 스토리지 활용률 극대화
- 서비스 다운타임 없는 무중단 **온라인 마이그레이션** 및 스냅샷 기반 데이터 보호

#### 한줄 요약
- 논리-물리 계층 분리로 씬 프로비저닝과 무중단 데이터 재배치를 실현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 LUN(Virtual LUN)**: 물리 디스크 구성과 무관하게 호스트 서버에 단일 가상 드라이브로 노출되는 논리 볼륨.
- **스토리지 풀(Storage Pool)**: 이기종 물리 디스크들의 용량을 통합 집적하여 가상 볼륨에 동적으로 공간을 제공하는 자원 풀.

</details>

```text
[스토리지 가상화 아키텍처]
|-- 호스트 서버 계층 (Virtual LBA 기반 블록 I/O 요청)
|-- 가상화 매핑 엔진 (Virtualization Controller / SDS Engine)
|   |-- 매핑 메타데이터 (Virtual LBA <-> Physical Extent 변환 테이블)
|   |-- 씬 프로비저닝 및 동적 블록 할당기
|   `-- 무중단 복제 및 스냅샷 관리자
`-- 이기종 물리 스토리지 풀 (All-Flash NVMe·HDD SAS 어레이)
```

선의 의미: 계층 및 주소 변환 I/O 흐름

| 구성요소 | 책임 |
|:---|:---|
| **가상 LUN** | 물리 스토리지 복잡성을 은닉하고 호스트에 표준 블록 디바이스 제공 |
| 가상화 매핑 엔진 | 가상 LBA와 물리 디스크 익스텐트 간의 실시간 주소 변환 및 I/O 라우팅 |
| 매핑 메타데이터 | 가상 주소와 실제 물리 디스크 위치 간의 대응 관계를 기록한 NVRAM 테이블 |
| **스토리지 풀** | 이기종 스토리지 용량을 집적하여 가상 볼륨에 물리 익스텐트 동적 공급 |
| 물리 스토리지 어레이 | All-Flash, HDD 등 실제 영구 데이터를 저장하는 백엔드 하드웨어 |

#### 한줄 요약
- 가상 LUN, 가상화 매핑 엔진, 메타데이터 테이블, 물리 스토리지 풀이 통합되어 가상화를 구현한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **익스텐트 할당(Extent Allocation)**: 씬 프로비저닝 볼륨에서 미할당 블록에 최초 쓰기 요청 인입 시 물리 풀에서 블록 단위(4KB~4MB)를 동적 바인딩하는 절차.

</details>

```text
호스트 서버가 가상 LUN의 특정 LBA로 쓰기(Write) 요청 전송
        │
   가상화 엔진이 메모리 내 매핑 메타데이터 테이블 조회
        │
   해당 가상 블록에 물리 익스텐트가 이미 할당되어 있는가?
   ┌────┴─────┐
  예           아니오 (최초 쓰기)
   │             │
해당 물리 주소로  스토리지 풀에서 새 물리 익스텐트 동적 할당
즉시 쓰기 수행    │
   │        물리 디스크에 실제 데이터 기록
   │             │
   └────┬────────┘
        │
   매핑 메타데이터 테이블 원자적(Atomic) 갱신 및 호스트 완료 응답
```

#### 한줄 요약
- 가상 쓰기 요청 → 메타데이터 조회 → 씬 프로비저닝 동적 익스텐트 할당 → 물리 쓰기 및 메타데이터 갱신 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **호스트 기반(Host-Based)**: OS 커널 레벨(LVM, vSAN)에서 가상화를 처리하는 방식.
- **네트워크 기반(Network-Based)**: SAN 스위치나 전용 어플라이언스에서 이기종 스토리지를 통합하는 방식.
- **배열 기반(Array-Based)**: 메인 스토리지 컨트롤러가 하위 스토리지를 가상화하는 방식.

</details>

| 스토리지 가상화 | 호스트 기반 (Host-Based : LVM) | 네트워크 기반 (Network-Based : SAN) | 스토리지 배열 기반 (Array-Based) |
|:---|:---|:---|:---|
| 가상화 구현 위치 | 호스트 OS 커널 드라이버/LVM | SAN 스위치 패브릭 또는 전용 어플라이언스 | 메인 스토리지 컨트롤러 펌웨어 |
| 이기종 지원성 | 단일 호스트 내부 한정, 이기종 수용 | SAN 망 내 모든 벤더 이기종 스토리지 통합 | 하위 SAS/FC 확장 인클로저 및 특정 장치 |
| 장단점 및 한계 | 호스트 CPU 자원 소모 및 공유 제한 | 대규모 이기종 통합 우수, 어플라이언스 병목 | 최고 I/O 성능, 특정 벤더 종속성(Lock-in) |

#### 한줄 요약
- 단일 서버는 호스트 기반, 대규모 이기종 SAN 통합은 네트워크 기반, 고성능 전용망은 배열 기반 가상화를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CBT(Changed Block Tracking)**: 무중단 데이터 마이그레이션 또는 백업 시 초기 전체 복제 후 변경된 블록만 비트맵으로 추적하여 최종 차분 동기화하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 씬 프로비저닝 오버커밋으로 인한 물리 공간 고갈 | 사용률 임계치(80%) 감시 및 자동 스토리지 풀 확장 | 디스크 용량 부족(Out-of-Space) 쓰기 실패 방지 |
| 가상화 컨트롤러 장애 시 전체 I/O 중단 | 액티브-액티브 듀얼 컨트롤러 및 NVRAM 메타데이터 미러링 | 단일 장애점(SPOF) 제거 및 고가용성(HA) 확보 |
| 무중단 온라인 이관 중 실시간 쓰기로 불일치 | **변경 블록 추적(CBT)** 기반 최종 델타 동기화 적용 | 서비스 중단 없는 무결점 무중단 데이터 마이그레이션 |
| 다중 가상 LUN 간 I/O 경합으로 인한 성능 저하 | 가상 볼륨별 QoS(IOPS/대역폭) 상한 및 하한 정책 수립 | 미션 크리티컬 워크로드의 최소 성능 확정적 보장 |

#### 한줄 요약
- 임계치 기반 용량 관리, 듀얼 컨트롤러 HA, CBT 무중단 마이그레이션, 볼륨 QoS를 통해 안정성을 완성한다.

## Ⅶ. 결론

- 하이브리드 클라우드 인프라는 **소프트웨어 정의 스토리지(SDS)** 및 **네트워크 기반 가상화**를 채택하고, **CBT 무중단 이관**으로 유연성 극대화

#### 한줄 요약
- 스토리지 가상화는 벤더 종속성을 탈피하고 자원 활용률을 극대화하는 클라우드 인프라의 핵심 저장 기술이다.
