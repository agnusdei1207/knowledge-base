## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스토리지 가상화(Storage Virtualization)**: 물리적으로 파편화된 이기종(Heterogeneous) 스토리지 자원들을 추상화하여 단일 논리 스토리지 풀(Pool)로 통합 관리하는 기술.
- **논리 저장 계층(Logical Storage Layer)**: 서버 호스트와 물리 스토리지 사이에서 주소 매핑 및 프로비저닝을 중간 제어하는 소프트웨어/하드웨어 계층.
- **이기종 스토리지(Heterogeneous Storage)**: 벤더, 전송 프로토콜(FC/iSCSI/SAS), 매체(NVMe/SSD/HDD)가 각기 다른 스토리지 서브시스템 그룹.

</details>

- 정의/개념: 이기종 물리 저장장치 자원을 추상화 매핑 계층을 통해 통일된 논리 볼륨(Logical Volume) 및 스토리지 풀로 전환 제공하는 **스토리지 가상화**
- 배경/필요성: 벤더별 독립 스토리지 파편화에 따른 자원 유휴화 해소, 오프라인 이동 불편성 단축 및 동적 용량 할당 요구성

#### 한줄 요약

- 스토리지 가상화는 이기종 스토리지를 통합된 논리 저장공간으로 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **논리·물리 분리(Logical-Physical Separation)**: 서버 호스트가 인식하는 LUN 주소와 실제 데이터를 보유한 물리 디스크 주소를 매핑 테이블을 통해 수평 분리하는 속성.
- **씬 프로비저닝(Thin Provisioning)**: 실제 물리 용량을 사전 선할당하지 않고, 실 데이터 쓰기 시점에 동적 할당하여 저장 효율성을 높이는 가상화 기술.
- **온라인 마이그레이션(Online Migration)**: 호스트 I/O를 유지하며 데이터를 다른 물리 스토리지로 단계적으로 재배치하는 기술.

</details>

- 물리 디스크 바인딩을 끊어내는 **논리·물리 분리** 추상화 매핑
- 가상 용량을 유연하게 선할당 수용하는 **씬 프로비저닝**
- 서비스 I/O를 유지하며 물리 장비를 교체하는 **온라인 마이그레이션**

#### 한줄 요약

- 매핑 계층의 위치 독립성과 지연·장애 전파 위험이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **논리 볼륨(Logical Volume)**: 호스트가 인식하는 가상의 단일 드라이브 래퍼.
- **스토리지 풀(Storage Pool)**: 이기종 물리 디스크 디바이스들의 용량을 하나로 집합해 둔 전체 자원 영역.
- **매핑 메타데이터(Mapping Metadata)**: 논리 LBA 주소와 물리 디스크 익스텐트(Extent) 간의 변환 정보를 상주 관리하는 인메모리 테이블.

</details>

```text
                         [매핑 메타데이터]
                                  |
                                  |
[논리 볼륨] -- [매핑•제어 엔진] -- [스토리지 풀]
```

선의 의미: 매핑·제어 엔진이 상단의 매핑 메타데이터를 참조하여 논리 볼륨 요청을 물리 스토리지 풀 주소로 실시간 변환하는 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 논리 볼륨 | 서버 호스트에게 단일 고성능 블록 디바이스 LUN 인가 |
| 매핑•제어 엔진 | LBA 주소 변환, **씬 프로비저닝** 동적 할당 및 마이그레이션 제어 |
| 매핑 메타데이터 | 논리 블록과 물리 익스텐트의 **매핑 메타데이터** 및 저널 저장 |
| 스토리지 풀 | NVMe, SSD, HDD 등 이기종 물리 자원 집적 및 **RAID** 보호 |

#### 한줄 요약

- 매핑 메타데이터로 논리 볼륨과 물리 풀을 연결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **주소 매핑(Address Mapping)**: 호스트 LBA 요청을 물리 스토리지 풀의 익스텐트 위치로 변환하는 작업.
- **원자적 반영(Atomic Commit)**: 매핑 테이블 갱신 시 전원 차단 등 예외 발생 시에도 불완전 매핑이 기록되지 않도록 Transaction 처리하는 기법.

</details>

```text
[논리 쓰기 요청]
        │
        ▼
1. 주소 매핑 조회
        │
        ▼
2. 물리 익스텐트 예약
        │
        ▼
3. 데이터•체크섬 기록
        │
        ▼
4. 매핑 원자적 확정
        │
        ▼
[논리 I/O 완료 반환]
```

### 동작 원리

1. **주소 매핑 조회**: 호스트의 **논리 볼륨** LBA 쓰기 요청 수용 및 **매핑 메타데이터** 조회.
2. **물리 익스텐트 예약**: **스토리지 풀** 내 신규 물리 익스텐트 할당 (**씬 프로비저닝** 적용).
3. **데이터·체크섬 기록**: 실제 물리 디스크 상에 데이터 블록 및 체크섬 쓰기 인가.
4. **매핑 원자적 확정**: 물리 쓰기 완결 후 매핑 메타데이터를 **원자적 반영(Atomic Commit)** 처리하여 논리 주소 바인딩 완료.

#### 한줄 요약

- 물리 데이터 기록 후 원자적 반영으로 매핑을 확정해야 장애가 발생해도 논리 주소가 미완료 데이터를 가리키지 않는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Host-Based Virtualization**: 서버 OS 내 LVM(Logical Volume Manager) 소프트웨어를 통해 스토리지 가상화를 구현하는 방식.
- **Network-Based Virtualization**: SAN 전용 가상화 어플라이언스/스위치 상에서 이기종 스토리지 어레이들을 통합 가상화하는 방식.
- **Array-Based Virtualization**: 특정 스토리지 어레이 컨트롤러가 타사 외장 스토리지를 하부에 종속시켜 가상화하는 방식.

</details>

| 비교 항목 | Host-Based | Network-Based (Appliance) | Array-Based |
|:---|:---|:---|:---|
| 가상화 위치 | 서버 호스트 OS (LVM/Volume Manager) | SAN 전용 가상화 어플라이언스 노드 | 스토리지 메인 어레이 컨트롤러 내 |
| 확장성/범위 | 서버 단위 한정, 이기종 스토리지 수용 | 산하 모든 **이기종 스토리지** 통합 가상화 | 해당 컨트롤러에 하부 연결된 장비만 한정 |
| 오버헤드 | 호스트 CPU·메모리 부하 증가 | 어플라이언스 경유 지연과 장애 영역 추가 | 특정 벤더 스토리지 어레이 종속성 |

#### 한줄 요약

- 가상화가 포괄해야 하는 서버•배열 범위와 허용 병목에 따라 호스트, 네트워크 또는 배열 기반 방식을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CBT(Changed Block Tracking)**: 데이터 이동 중 변경된 블록만 추적하여 차분 복제하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **씬 프로비저닝** 오버커밋에 따른 물리 풀 고갈 | 용량 임계치 설정과 자동 확장·경보 | 쓰기 중단 전 용량 부족 대응 |
| 가상화 어플라이언스 장애 시 전체 LUN 중단 위험 | 컨트롤러 이중화와 메타데이터 복제 | 제어 노드 단일 장애 시 서비스 유지 |
| 온라인 마이그레이션 도중 데이터 불일치 발생 | **CBT**와 체크섬·최종 동기화 검증 | 이동 중 변경 블록의 정합성 확보 |

> 사례: **Network-Based 가상화** 어플라이언스 적용을 통한 이기종 SAN 어레이 통합 및 **Thin Provisioning** 수용

#### 한줄 요약

- 변경 블록 추적으로 서비스 중 온라인 이동 정합성을 유지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스토리지 가상화 선택 기준(Storage Virtualization Selection Criteria)**: 이기종 어레이 범위, 성능 지연 타깃, 비용 및 운용 복잡성에 기반한 아키텍처 수립 체계.

</details>

- 단일 호스트는 **Host-Based**, 다중 어레이는 **Network-Based**, 단일 벤더는 **Array-Based** 선택

#### 한줄 요약

- 단일 호스트는 호스트 기반, 다중 어레이는 네트워크 기반 가상화를 선택한다.
