## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스토리지 가상화(Storage Virtualization)**: 델, HP, 넷앱 등 제조사가 다르고 파편화된 디스크들을 멱살 잡고 하나로 묶어서, 서버한테는 "이거 그냥 존나게 큰 1개의 삼성 하드야"라고 뻥을 치는 환술 기술이다.
- **논리 저장 계층(Logical Storage Layer)**: 서버와 실제 디스크 사이에 끼어들어서, 가짜 주소와 진짜 주소를 연결해 주는 사기꾼 통역사(매핑 엔진) 계층이다.
- **이기종 스토리지(Heterogeneous Storage)**: 삼성 SSD, 시게이트 HDD, NVMe, iSCSI 등 족보도 없고 속도도 제각각인 온갖 잡다한 디스크들의 난장판 집합소이다.

</details>

- 정의: 제조사도 다르고 속도도 다른 이기종 물리 저장장치 자원들을 추상화 매핑 계층을 통해 통일된 논리 볼륨(Logical Volume) 및 거대한 하나의 스토리지 풀로 전환 제공하는 **스토리지 가상화** 기술
- 배경: 부서마다 벤더별 스토리지(이기종)를 따로 사서 공간이 남아도는데도 서로 나눠 쓰지 못하는 비효율성을 박살 내고, 서버 끄지 않고 데이터를 맘대로 이사 다니게 만들기 위함

#### 한줄 요약

- 제조사가 다른 짬뽕 디스크들을 하나로 묶어서, 서버한테는 거대한 단일 드라이브처럼 속여서 팔아먹는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **논리·물리 분리(Logical-Physical Separation)**: 서버가 데이터를 쓸 때 진짜 5번 디스크에 쓰는지 10번 디스크에 쓰는지 알 바 아니게, 눈을 가려버리는 치명적인 물리 종속성 단절이다.
- **씬 프로비저닝(Thin Provisioning)**: 실제 물리 하드가 10TB밖에 없으면서 서버한테는 "너 100TB짜리 하드 줄게" 하고 뻥을 쳐놓고, 진짜 데이터가 들어올 때만 디스크를 쪼금씩 할당하는 폰지 사기 기술이다.
- **온라인 마이그레이션(Online Migration)**: 서버 끄고 짐 쌀 필요 없이, 서비스 켜놓고 낡은 하드의 데이터를 새 하드로 몰래 옮겨치기 하는 신기 방기한 이사 기술이다.

</details>

- 서버는 가짜 드라이브(LUN)만 보고 실제 데이터가 어느 회사 디스크에 박혀있는지 알 바 아니게 끊어버리는 **논리 물리 분리** 추상화를 제공함.
- 실제 물리 하드가 없으면서도 서버한테는 대용량을 줬다고 거짓말을 쳐놓고, 데이터가 진짜 들어올 때만 디스크를 쪼금씩 할당하는 얌체 같은 **씬 프로비저닝**을 수용함.
- 서비스 끄고 짐 쌀 필요 없이, 넷플릭스 켜놓은 상태에서 낡은 하드의 데이터를 새 하드로 몰래 옮겨치기 하는 **온라인 마이그레이션**을 지원함.

#### 한줄 요약

- 진짜 디스크 주소를 감추고 가짜 용량을 뻥튀기하며, 서버 켜놓은 상태에서 디스크를 갈아 끼울 수 있는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **논리 볼륨(Logical Volume)**: 물리 하드가 100개로 쪼개졌든 상관없이, 서버 호스트 눈에는 아주 예쁘게 포장된 1개의 C드라이브처럼 보이게 만든 가짜 껍데기이다.
- **스토리지 풀(Storage Pool)**: 제조사 따위 개나 줘버리고 온갖 디스크들을 하나로 짬뽕시켜서 거대하게 묶어놓은 짬처리 저장소이다.
- **매핑 메타데이터(Mapping Metadata)**: "가짜 주소 1번은 삼성 하드 5번에, 가짜 주소 2번은 인텔 하드 10번에 있다"고 적어둔 치명적인 인메모리 장부이다.
- **복수 배열 독립 디스크(Redundant Array of Independent Disks, RAID)**: 싸구려 하드 여러 개를 묶어서 속도를 미친 듯이 올리거나, 하나 고장 나도 안 뻗게 막아주는 방패 마법이다.

</details>

```text
[ 이기종 디스크 짬처리 및 가짜 드라이브 뻥튀기 프레임워크 ]
                          [ 매핑 메타데이터 (가짜-진짜 연결 장부) ]
                                          │
[ 논리 볼륨 (예쁜 가짜 C드라이브) ] ── [ 매핑 제어 엔진 (사기꾼 통역사) ] ── [ 스토리지 풀 (잡동사니 디스크 무덤) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **논리 볼륨** | 물리 하드가 몇 개로 쪼개졌든 상관없이, 서버 호스트 눈에는 아주 예쁘게 포장된 1개의 C드라이브(LUN)처럼 보이게 만든 껍데기 |
| 매핑•제어 엔진 | 서버가 껍데기에 데이터를 쓰면 진짜 물리 하드 주소로 변환해주고(매핑), 뻥튀기 공간(**씬 프로비저닝**)을 쥐락펴락하는 두뇌 |
| **매핑 메타데이터** | "가짜 주소 1번은 삼성 하드 5번에, 가짜 주소 2번은 인텔 하드 10번에 있다"고 적어둔 치명적인 인메모리 장부 |
| **스토리지 풀** | 제조사 따위 개나 줘버리고 온갖 디스크들을 하나로 짬뽕시켜서 **RAID**로 묶어놓은 거대한 짬처리 저장소 |

#### 한줄 요약

- 잡다한 디스크(스토리지 풀)를 엮어서 매핑 장부에 적어두고, 서버한테는 깔끔한 가짜 드라이브(논리 볼륨)만 보여준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **주소 매핑(Address Mapping)**: 서버가 부르는 가짜 주소(LBA)를 듣고, "아, 그건 진짜 디스크 5번 트랙 3섹터에 있어" 하고 잽싸게 통역해 주는 과정이다.
- **원자적 반영(Atomic Commit)**: 장부에 펜으로 적다가 전기 나가면 반쪽짜리 쓰레기 데이터가 되니까, "다 쓰거나 아예 안 썼던 걸로 치거나(All or Nothing)" 하는 얄짤없는 DB 트랜잭션 룰이다.

</details>

```text
[ 이기종 스토리지 추상화 및 씬 프로비저닝 쓰기 십자포화 흐름 ]
                                 │
                                 ▼
         [ 1. 가짜 주소 검문: 서버가 데이터 쓰면 매핑 장부를 까서 확인함 ]
                                 │
                                 ▼
      [ 2. 뻥튀기 할당: 실제 공간 없으면 그제야 짬처리 풀에서 디스크 떼어옴 ]
                                 │
                                 ▼
    [ 3. 무자비한 기록: 할당받은 물리 디스크에 데이터랑 에러 체크섬 냅다 꽂아버림 ]
                                 │
                                 ▼
    [ 4. 장부 쾅쾅 확정: 다 쓰면 '가짜=진짜' 장부 갱신 (쓰다 죽으면 얄짤없이 롤백) ]
```

### 동작 원리

1. 가짜 주소 검문: 호스트가 가상 드라이브(**논리 볼륨**)에 데이터를 쏘면 엔진이 **매핑 메타데이터** 장부를 펴봄.
2. 뻥튀기 공간 할당: 아직 실제 공간이 없으면(**씬 프로비저닝**), 그제야 진짜 **스토리지 풀**에서 디스크 공간(익스텐트)을 떼옴.
3. 무자비한 기록: 할당받은 실제 물리 디스크에 데이터와 에러 잡는 체크섬을 무자비하게 꽂아버림.
4. 장부 쾅쾅 확정: 데이터가 다 써지면 "가짜 주소 = 진짜 주소" 라고 장부를 갱신하는데, 쓰다 전기 나가면 아예 취소해 버리는 **원자적 반영**을 얄짤없이 적용함.

#### 한줄 요약

- 서버가 쓸 때 장부 확인하고 진짜 공간 떼어준 다음, 쓰기 성공해야만 장부에 완전히 박아 넣는다(원자적 반영).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **호스트 기반 가상화(Host-Based Virtualization)**: 비싼 장비 살 돈 없어서 서버 OS 자체 기능(LVM)으로 어떻게든 하드 묶어서 버텨보는 흙수저 방식이다.
- **네트워크 기반 가상화(Network-Based Virtualization)**: SAN 스위치단에 수천만 원짜리 장비를 박아서, 밑에 있는 이기종 스토리지를 싹 다 통합하는 귀족형 방식이다.
- **배열 기반 가상화(Array-Based Virtualization)**: 대장 스토리지 장비가 지 밑에 굴러다니는 싸구려 디스크들만 노예처럼 부리는 방식이다.

</details>

| 비교 항목 | **호스트 기반 가상화** (Host-Based) | **네트워크 기반 가상화** (Network-Based) | **배열 기반 가상화** (Array-Based) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 비싼 스토리지 장비 살 돈 없어서 깡통 서버 여러 대에 리눅스(LVM) 깔아서 묶어 쓸 시 | 돈지랄 좀 해서 삼성, IBM, 델 스토리지 수십 대를 짬뽕해서 하나처럼 통제 관리해야 할 시 | 메인 스토리지가 대장 노릇 하면서 밑에 굴러다니는 싸구려 디스크들을 노예처럼 부릴 시 |
| 아키텍처 핵심 구현 특징 | 서버 운영체제가 CPU랑 램을 직접 갉아먹어가며 가짜 드라이브를 소프트웨어적으로 깎아 만듦 | SAN 스위치단에 비싼 전용 어플라이언스(장비)를 달아서 그놈이 밑에 놈들 군기를 다 잡음 | 대장 스토리지 컨트롤러에 꽂힌 놈들만 멱살 잡고 통합하는 폐쇄적인 하청업체 구조 |
| 극복해야 할 태생적 한계점 | 서버 CPU가 데이터 처리하느라 헐떡거리고, 다른 서버랑 묶어서 쓰기가 빡세거나 불가능함 | 중간에 낀 어플라이언스가 뻗어버리면 밑에 스토리지 수십 대가 다 같이 저세상 가는 대참사 | 대장 스토리지 벤더한테 목줄이 잡혀서 평생 그 회사 비싼 장비만 사야 하는 노예 계약(종속성) |

#### 한줄 요약

- 서버 자체로 묶으면 호스트, 중간 장비로 다 묶으면 네트워크, 메인 스토리지가 밑에 놈만 묶으면 배열 기반이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **변경 블록 추적(Changed Block Tracking, CBT)**: 하드 복사(이사) 10시간 걸리는데 그동안 바뀐 내용만 귀신같이 찾아내서 막판에 덮어씌워 주는 스마트한 추적 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **씬 프로비저닝**으로 뻥튀기 공간 팔아먹었다가 진짜로 물리 디스크 꽉 차버리면 서버들 단체로 뻗는 폰지 사기 재앙 | 용량 80% 차면 알람 울리게 세팅하고 뻗기 전에 재빨리 물리 디스크 쑤셔 넣는 자동 확장 떡칠 | 하드 모자라서 쓰기 에러 나고 시스템 날아가는 최악의 대참사 원천 방어 |
| 가상화 어플라이언스 장비가 죽어버리면 그 밑에 멀쩡한 디스크들까지 다 같이 마비되는 치명적 병목 | 컨트롤러 2개 달고 매핑 장부(메타데이터)를 실시간으로 미러링 복제해서 한 놈 죽어도 멱살 잡고 버팀 | 대가리(제어 노드)가 터져도 서비스는 단 1초도 안 멈추는 극강의 무중단 아키텍처 사수 |
| 데이터 이사(온라인 마이그레이션) 중에 서버가 데이터를 계속 바꿔버려서 새집이랑 헌집 데이터가 꼬이는 끔찍한 불일치 | **변경 블록 추적**(CBT)을 돌려 이사 중에 바뀐 놈들만 얄짤없이 솎아내서 막판에 한 번 더 엎어침 | 넷플릭스 켜놓고 하드 갈아끼워도 데이터가 0.001바이트도 안 깨지는 완벽한 무결성 보장 |

#### 한줄 요약

- 용량 뻥튀기 사기 치다 걸리기 전에 디스크 채우고, 중간 통역기 2대 달고, 이사 중 바뀐 데이터는 CBT로 잡아내라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스토리지 가상화 선택 기준(Storage Virtualization Selection Criteria)**: 돈이 얼마나 있는지, 벤더 종속(노예 계약)될 건지, 디스크가 얼마나 파편화됐는지 따져보고 어떤 가상화 방식을 쓸지 결정하는 잣대이다.

</details>

- **스토리지 가상화 선택 기준** 원칙에 따라, 깡통 서버는 **호스트 기반**, 돈 발라 이기종 싹 다 묶으려면 **네트워크 기반**, 한 회사 벤더 노예 계약은 **배열 기반** 채택 기조 확립함

#### 한줄 요약

- 돈 없으면 호스트(LVM)로 때우고, 제조사 짬뽕이면 네트워크 장비 사고, 특정 회사에 올인했으면 배열 기반 써라.
