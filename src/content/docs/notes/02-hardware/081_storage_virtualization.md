## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스토리지 가상화(Storage Virtualization)**: 다수의 물리적 저장장치(All-Flash NVMe, SAS HDD, 이기종 SAN 어레이)를 논리적으로 통합 추상화하여, 호스트 서버에 물리 하드웨어 종속성이 없는 단일 가상 스토리지 풀(Pool)과 가상 볼륨(Virtual LUN)으로 제공하는 기술.
- **논리-물리 주소 매핑(LBA Mapping)**: 호스트가 접근하는 가상 블록 주소(Virtual LBA)와 백엔드 실제 물리 디스크의 블록 주소(Physical Extent)를 실시간으로 상호 변환하는 추상화 계층.

</details>

- 정의/개념: 이기종 물리 스토리지를 단일 자원 풀로 통합 추상화하고, **논리-물리 매핑(Virtual LBA ➔ Physical Extent)**을 통해 씬 프로비저닝과 무중단 마이그레이션을 제공하는 **스토리지 가상화(Storage Virtualization) 아키텍처**
- 배경/필요성: 벤더별 스토리지의 사일로화(Silo)로 인한 **용량 불균형, 스토리지 교체 시 서비스 중단(Downtime) 및 복잡한 관리 오버헤드 극복**

#### 한줄 요약
- 스토리지 가상화는 물리 스토리지의 복잡성을 은닉하고 논리-물리 매핑을 통해 동적 용량 관리와 무중단 마이그레이션을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **씬 프로비저닝(Thin Provisioning)**: 호스트에는 대용량 가상 볼륨(예: 10TB)을 즉시 할당하되, 실제 물리 디스크 공간은 데이터가 실제로 쓰이는 시점에만 블록 단위로 동적 할당하는 기술.
- **온라인 데이터 마이그레이션(Online Migration)**: 서비스 운영 중단 없이 백그라운드에서 데이터를 구형 스토리지에서 신형 스토리지로 실시간 이관하는 무중단 재배치 기능.

</details>

- 물리 디스크와의 완전한 디커플링: **논리-물리 주소 매핑 분리**를 통해 호스트 설정 변경 없이 백엔드 물리 스토리지 자유로운 증설 및 교체
- 자원 활용률 극대화: **씬 프로비저닝(Thin Provisioning)** 및 중복제거/압축 기술을 결합하여 물리 디스크 활용률을 기존 30%에서 80% 이상으로 향상
- 무중단 고가용성: 서비스 다운타임이 0인 **온라인 데이터 마이그레이션** 및 스토리지 풀 간의 실시간 미러링 데이터 보호

#### 한줄 요약
- 주소 매핑 분리로 씬 프로비저닝과 다운타임 없는 온라인 데이터 재배치를 실현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 LUN(Virtual LUN)**: 물리 디스크의 실제 위치 및 RAID 구성과 무관하게 호스트 서버에 표준 블록 디바이스로 노출되는 가상 볼륨.
- **스토리지 풀(Storage Pool)**: 이기종 물리 디스크들의 가용 공간을 하나의 거대한 자원 저장소로 집적하여 가상 볼륨에 물리 익스텐트(Extent)를 동적 배분하는 엔진.

</details>

```text
[스토리지 가상화 3계층 아키텍처]
 ┌─ [1. 호스트 서버 계층 (Host Layer)] ────── 가상 볼륨 접근 (Virtual LBA 0 ~ N 기반 I/O)
 │                                                    │ (Virtual LUN 1, Virtual LUN 2)
 ├─ [2. 가상화 매핑 엔진 계층 (SDS Engine)] ──────────┴──────────────────────────────────────┐
 │   ├─ [매핑 메타데이터 엔진] ────────── Virtual LBA ◄───► Physical Extent 변환 테이블    │
 │   ├─ [씬 프로비저닝 할당기] ────────── 최초 쓰기 시 물리 블록 동적 바인딩 엔진            │
 │   ├─ [온라인 마이그레이션 / CBT 관리자] ─ 무중단 백그라운드 데이터 블록 이관 엔진          │
 │   └─ [볼륨 QoS 컨트롤러] ───────────── IOPS / 대역폭 상한·하한 제어기                     │
 └──────────────────────┬───────────────────────────────┬───────────────────────────────┬───┘
                        │                               │                               │
 ┌──────────────────────▼──────┐         ┌──────────────▼──────────────┐ ┌──────────────▼───┐
 │ [스토리지 풀 A: All-Flash]  │         │ [스토리지 풀 B: SAS HDD]     │ │ [스토리지 풀 C]  │
 └─────────────────────────────┘         └─────────────────────────────┘ └──────────────────┘
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어/소프트웨어 소속 및 주소 변환 파이프라인; 가상화 엔진이 가상 LBA를 물리 익스텐트로 변환하여 이기종 풀로 라우팅함

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **가상 LUN** | 가상화 상단 | 물리적 위치를 은닉하고 호스트 OS에 단일 고속 블록 디바이스 제공 | Virtual Block LBA |
| **가상화 매핑 엔진**| 가상화 제어단 | 가상 LBA와 물리 디스크 익스텐트 간의 **실시간 주소 변환 및 I/O 라우팅** | SDS 가상화 엔진 |
| **매핑 메타데이터** | NVRAM/캐시단 | 가상 주소와 물리 디스크 위치 간의 대응 테이블을 원자적(Atomic) 관리 | 초고속 인메모리 테이블 |
| **씬 프로비저닝 할당기**| 자원 관리단 | 미할당 블록에 쓰기 발생 시 스토리지 풀에서 4KB~4MB 익스텐트 동적 공급 | 공간 오버커밋 지원 |
| **이기종 스토리지 풀**| 물리 백엔드단 | All-Flash NVMe, SAS HDD, 외부 SAN 어레이의 물리 용량 집적 | 풀 단위 확장 |

#### 한줄 요약
- 가상 LUN, 가상화 매핑 엔진, 메타데이터 테이블, 씬 프로비저닝 할당기 및 물리 스토리지 풀로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **익스텐트 동적 할당(Extent Allocation)**: 씬 프로비저닝 환경에서 호스트가 미할당 가상 LBA에 데이터를 처음 기록할 때, 스토리지 풀에서 실제 물리 블록을 떼어 매핑하는 절차.

</details>

```text
1. 호스트 서버: 가상 LUN의 특정 가상 블록(Virtual LBA)으로 쓰기(Write) 요청 전송
                      │
                      ▼
2. 가상화 매핑 엔진: 인메모리 매핑 메타데이터 테이블 조회
                      │
                      ▼
3. 해당 가상 LBA에 물리 디스크 익스텐트(Physical Extent)가 이미 할당되어 있는가?
   ┌──────────────────┴──────────────────┐
[ 이미 할당됨 (기존 블록 덮어쓰기) ]  [ 미할당 상태 (씬 프로비저닝 최초 쓰기) ]
   │                                     │
   ▼                                     ▼
4. 매핑된 물리 디스크 주소로             4. 백엔드 스토리지 풀에서 새로운 물리 익스텐트 동적 할당
   데이터 즉시 기록                      │
   │                                     ▼
   │                                  5. 실제 물리 디스크 블록에 데이터 기록
   │                                     │
   │                                     ▼
   │                                  6. 매핑 메타데이터 테이블에 [Virtual LBA ➔ Extent] 원자적 갱신
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 호스트 서버로 I/O 쓰기 완료(ACK) 응답 반환
```

분기 결과: **씬 프로비저닝을 통해** 실제 쓰기가 발생하는 순간에만 물리 용량을 소비하므로 스토리지 낭비를 원천 차단함

#### 한줄 요약
- 가상 쓰기 요청 ➔ 메타데이터 조회 ➔ 씬 프로비저닝 동적 익스텐트 할당 ➔ 물리 기록 및 메타데이터 갱신 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **호스트 기반 가상화(Host-Based)**: LVM(논리 볼륨 관리자)이나 vSAN처럼 호스트 OS 커널 레벨에서 스토리지를 가상화하는 방식.
- **네트워크 기반 가상화(Network-Based)**: SAN 스위치 패브릭 또는 전용 SDS 가상화 어플라이언스에서 이기종 스토리지를 통합하는 방식.
- **배열 기반 가상화(Array-Based)**: 특정 메인 스토리지 컨트롤러 펌웨어가 하위 외장 스토리지를 가상화하여 수용하는 방식.

</details>

| 스토리지 가상화 방식 | 호스트 기반 (Host-Based / LVM, vSAN) | 네트워크 기반 (Network-Based / SAN SDS) | 스토리지 배열 기반 (Array-Based) |
|:---|:---|:---|:---|
| 가상화 구현 계층 | **호스트 OS 커널 드라이버 / 하이퍼바이저** | **SAN 스위치 패브릭 또는 전용 어플라이언스**| 메인 스토리지 어레이 컨트롤러 펌웨어 |
| 이기종 스토리지 수용력| 단일 호스트 내부 장치로 한정 | **SAN 망 내 모든 벤더 이기종 스토리지 통합** | 특정 인증된 하위 확장 인클로저 및 장비 |
| 호스트 CPU 부하 | 부하 발생 (가상화 연산 수행) | **부하 0 (전용 패브릭/어플라이언스 처리)** | 부하 0 (스토리지 컨트롤러 처리) |
| 주요 적용 분야 | HCI(하이퍼컨버지드), 단일 서버 LVM | **대규모 엔터프라이즈 이기종 SAN 통합** | 하이엔드 엔터프라이즈 올플래시 스토리지 |

#### 한줄 요약
- 클라우드 HCI에는 호스트 기반, 대규모 이기종 통합에는 네트워크 기반, 고성능 전용망에는 배열 기반 가상화를 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **변경 블록 추적(Changed Block Tracking, CBT)**: 무중단 온라인 데이터 이관 중 초기 전체 복제 이후 새롭게 발생한 실시간 변경 블록만 비트맵으로 추적하여 최종 차분 동기화하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 씬 프로비저닝 오버커밋으로 인한 물리 스토리지 풀 공간 고갈 | **스토리지 풀 사용률 임계치(80%) 모니터링 및 자동 용량 확장** | Out-of-Space 쓰기 실패 및 시스템 중단 사전 방지 |
| 스토리지 가상화 컨트롤러 장애 시 전체 가상 볼륨 마비 | **액티브-액티브 듀얼 컨트롤러 및 NVRAM 메타데이터 미러링** | 단일 장애점(SPOF) 제거 및 100% 무중단 HA 보장 |
| 무중단 온라인 마이그레이션 중 실시간 쓰기 불일치 | **변경 블록 추적(CBT) 기반 최종 델타(Delta) 동기화 적용** | 서비스 무중단 상태에서 100% 데이터 정합성 이관 |
| 다중 가상 볼륨 간의 I/O 경합으로 인한 성능 간섭 | **가상 LUN별 IOPS 및 대역폭 QoS(Quality of Service) 정책 수립** | 미션 크리티컬 워크로드의 최소 성능 확정적 보장 |

#### 한줄 요약
- 실무에서는 임계치 모니터링으로 용량을 지키고, 듀얼 컨트롤러로 HA를 보장하며, CBT로 무중단 이관을 완성한다.

## Ⅶ. 결론

- 하이브리드 클라우드 데이터센터의 스토리지 효율성을 극대화하기 위해 **소프트웨어 정의 스토리지(SDS) 및 네트워크 기반 가상화 엔진을 표준 도입**하고, 물리 용량 최적화를 위해 **씬 프로비저닝 및 데이터 중복제거**를 연계하며, 서비스 연속성을 위해 **CBT 기반 무중단 온라인 마이그레이션 체계**를 필수 구축하는 차세대 스토리지 가상화 인프라 확립

#### 한줄 요약
- 스토리지 가상화는 벤더 종속성을 탈피하고 자원 활용률을 극대화하는 클라우드 인프라의 핵심 저장 기술이다.
