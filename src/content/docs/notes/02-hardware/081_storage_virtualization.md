## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Storage Virtualization(스토리지 가상화)**: 다수의 물리적 저장장치(HDD, SSD, SAN 어레이)를 논리적으로 통합 및 추상화하여 호스트 서버에 독립된 가상 스토리지 풀로 제공하는 기술.
- **Logical Storage Layer(논리 스토리지 계층)**: 호스트가 바라보는 논리 블록 주소(LBA)와 실제 물리 디스크의 블록 주소를 실시간으로 변환해 주는 매핑 추상화 계층.
- **Heterogeneous Storage(이기종 스토리지)**: 제조사, 프로토콜(FC, iSCSI, SAS, NVMe), 성능 규격이 서로 다른 다양한 스토리지 장비들의 집합.

</details>

- 정의/개념: 이기종(Heterogeneous) 물리 스토리지 디바이스들을 추상화(Abstraction) 매핑 계층을 통해 단일하고 통합된 논리적 스토리지 풀(Storage Pool) 및 가상 볼륨(Virtual Volume)으로 전환하여 제공하는 기술
- 배경/필요성: 벤더별 스토리지 사일로 파편화에 따른 용량 불균형 해소 및 무중단 온라인 마이그레이션을 통한 스토리지 TCO 절감 필요

#### 한줄 요약

- 이기종 물리 스토리지를 추상화하여 **단일 스토리지 풀 및 논리 볼륨(LUN)으로 통합 제공하는 기술**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Logical-Physical Separation(논리-물리 분리)**: 서버 호스트가 물리 디스크의 위치, RAID 레벨, 제조사를 알 필요 없이 표준 논리 LUN으로만 I/O를 수행하도록 분리하는 구조.
- **Thin Provisioning(씬 프로비저닝)**: 호스트에는 대용량 가상 볼륨을 미리 할당해 두고, 실제 물리 디스크 공간은 데이터가 실제로 기록되는 순간에만 동적으로 할당하는 기술.
- **Online Migration(무중단 온라인 마이그레이션)**: 서비스 중단(Downtime) 없이 백그라운드에서 데이터를 구형 스토리지에서 신형 스토리지로 실시간 이관하는 기능.

</details>

- 호스트 서버와 물리 디스크 간의 결합도를 완전히 제거하는 **논리-물리 주소 매핑 분리(Abstraction)**
- 디스크 가용률을 극대화하고 오버프로비저닝을 지원하는 **씬 프로비저닝(Thin Provisioning)**
- 스토리지 교체, 펌웨어 갱신, 성능 튜닝 시 서비스 중단을 없애는 **무중단 온라인 데이터 이관(Online Migration)**

#### 한줄 요약

- **논리-물리 주소 매핑 분리·씬 프로비저닝(Thin Provisioning) 자원 가상화·무중단 온라인 마이그레이션**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Virtual LUN(가상 논리 볼륨)**: 호스트 서버에 노출되는 가상 디스크 드라이브.
- **Mapping Metadata(매핑 메타데이터)**: 가상 볼륨의 블록 주소와 물리 디스크 익스텐트(Extent) 간의 1:1 대응 관계를 기록한 인메모리/NVRAM 테이블.
- **Storage Pool**: 이기종 디스크들의 용량을 통합하여 가상 볼륨 생성의 원천 공간을 제공하는 스토리지 자원 풀.

</details>

```text
[ 스토리지 가상화 논리-물리 매핑 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 서버 (Host OS : Virtual LUN 1, Virtual LUN 2 마운트)  │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 가상 논리 블록 주소 (Virtual LBA) I/O ]
┌──────────────────────────────┴──────────────────────────────┐
│ 가상화 매핑 엔진 (Virtualization Engine / SDS Controller)    │
│  ├─ 매핑 메타데이터 (Virtual LBA <──> Physical Extent 변환)  │
│  └─ 씬 프로비저닝, 스냅샷, 복제 제어 모듈                   │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 실제 물리 블록 I/O ]
┌──────────────────────────────┴──────────────────────────────┐
│ 이기종 스토리지 풀 (Dell, HPE, NetApp, NVMe-oF 어레이)       │
│  ├─ Storage Array A (All-Flash) ├─ Storage Array B (HDD 풀) │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트 논리 볼륨(Virtual LUN), 가상화 매핑 엔진, 매핑 메타데이터 및 이기종 물리 스토리지 풀 간의 스토리지 가상화 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 논리 볼륨(Virtual LUN) | 물리 디스크의 복잡성을 은닉하고 호스트 서버에 단일 가상 디스크 드라이브로 노출 |
| 가상화 매핑 엔진 | 가상 LBA와 물리 디스크 익스텐트 간의 실시간 주소 변환 및 씬 프로비저닝 제어 |
| 매핑 메타데이터 | 논리 블록 주소와 실제 물리 디스크 위치 간의 대응 관계를 기록한 인메모리/NVRAM 테이블 |
| 스토리지 풀(Storage Pool) | 이기종 디스크들의 용량을 통합 집적하여 가상 볼륨에 동적으로 공간을 공급하는 자원 풀 |

#### 한줄 요약

- **논리 볼륨(Virtual LUN)·가상화 매핑 엔진·매핑 메타데이터·이기종 물리 스토리지 풀(RAID)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Extent Allocation**: 씬 프로비저닝 볼륨에서 미할당 블록에 첫 쓰기(Write) 요청이 들어올 때 스토리지 풀에서 4KB~4MB 크기의 물리 블록 단위(Extent)를 새로 떼어주는 동작.

</details>

```text
[ 가상화 볼륨 I/O 처리 및 씬 프로비저닝 할당 시퀀스 ]
                         │
                         ▼
   [ 1. 호스트 서버가 가상 LUN 의 특정 LBA 로 쓰기(Write) 요청 전송 ]
                         │
                         ▼
   [ 2. 가상화 엔진이 매핑 메타데이터 테이블 조회 ]
        /                                               \
   [ 이미 물리 익스텐트 할당됨 ]                     [ 최초 쓰기 (미할당 블록) ]
        │                                               │
   [ 해당 물리 주소로 즉시 쓰기 ]                 [ 3. 스토리지 풀에서 새 익스텐트 동적 할당 ]
        │                                               │
        │                                         [ 4. 물리 디스크에 데이터 기록 ]
        │                                               │
        └───────────────────────┬───────────────────────┘
                                │
                                ▼
   [ 5. 매핑 메타데이터 테이블 원자적(Atomic) 갱신 및 호스트 완료 응답 ]
```

**동작 원리**

1. **쓰기 요청**: 호스트가 가상 LUN $0$번 블록에 데이터 기록 명령 전달
2. **메타데이터 조회**: 가상화 엔진이 메모리 내 주소 변환 테이블을 검색하여 대응하는 물리 디스크 및 섹터 식별
3. **동적 공간 할당**: 씬 프로비저닝 볼륨일 경우 미할당 블록에 대해 물리 풀에서 새 익스텐트(Extent) 바인딩
4. **물리 I/O 수행**: 해당 이기종 스토리지 어레이의 물리 블록에 실제 데이터 기록
5. **원자적 커밋**: 주소 매핑 테이블을 갱신하고 NVRAM/저널에 기록하여 정전 시에도 정합성 보장

#### 한줄 요약

- 호스트 I/O 인입 $\to$ **메타데이터 가상-물리 주소 변환 $\to$ 씬 프로비저닝 시 물리 익스텐트 동적 할당 $\to$ 물리 디스크 쓰기 $\to$ 원자적(Atomic) 메타데이터 커밋**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Host vs Network vs Array-Based Virtualization**:
  - Host-Based: 호스트 OS 소프트웨어(LVM/vSAN), 서버 자원 소모, 다중 서버 공유 제한
  - Network-Based: SAN 스위치/어플라이언스(SVC), 완전한 이기종 통합, 고성능
  - Array-Based: 스토리지 컨트롤러 펌웨어, 해당 벤더 환경 특화, 벤더 락인

</details>

| 구분 | 호스트 기반 가상화 (Host-Based : LVM) | 네트워크 기반 가상화 (Network-Based : SAN Appliance) | 스토리지 배열 기반 가상화 (Array-Based : Controller) |
|:---|:---|:---|:---|
| 가상화 구현 위치 | 호스트 OS 커널 드라이버/볼륨 관리자(LVM) | SAN 스위치 패브릭 또는 전용 어플라이언스 | 메인 스토리지 컨트롤러 펌웨어 |
| 이기종 지원 및 확장성 | 단일 호스트 내부 한정, 이기종 스토리지 수용 | SAN 망 내 모든 벤더 이기종 스토리지 통합 | 하위 SAS/FC 확장 인클로저 또는 벤더 지원 장치 |
| 한계 및 오버헤드 | 호스트 서버 CPU/메모리 자원 소모 | 전용 어플라이언스 병목 및 단일 실패 지점(SPOF) | 특정 스토리지 벤더 종속성(Lock-in) |

#### 한줄 요약

- 단일 서버는 **호스트 기반(LVM)**, 대규모 이기종 통합은 **네트워크 기반**, 전용 장비는 **배열 기반**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CBT(Changed Block Tracking)**: 무중단 데이터 마이그레이션 또는 백업 시 초기 전체 복제 후 변경된 블록만 비트맵으로 추적하여 최종 차분 동기화하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 씬 프로비저닝(Thin Provisioning) 환경에서 오버커밋(Overcommit)으로 인한 물리 스토리지 풀 고갈 위험 | **용량 사용률 임계치(80%) 모니터링** 및 스토리지 풀 자동 확장(Auto-Expansion) 정책 연동 | 디스크 용량 부족(Out-of-Space) 쓰기 실패 방지 |
| 가상화 어플라이언스 또는 메타데이터 서버 장애 시 전체 스토리지 I/O 마비 위험 | **액티브-액티브 듀얼 컨트롤러 구성** 및 NVRAM 기반 메타데이터 실시간 미러링 | 단일 장애점(SPOF) 제거 및 고가용성(HA) 확보 |
| 무중단 온라인 마이그레이션 중 실시간 쓰기 I/O로 인한 원본-대상 스토리지 간 데이터 불일치 | **변경 블록 추적(CBT, Changed Block Tracking)** 및 최종 델타 동기화 적용 | 서비스 중단 없는 무결점 데이터 이관 보장 |

#### 한줄 요약

- **Thin Provisioning 용량 임계치(80%) 자동 확장·듀얼 컨트롤러 메타데이터 미러링(HA)·CBT 기반 무중단 데이터 이관**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SDS(Software-Defined Storage)로의 발전**: 전용 하드웨어 어플라이언스를 탈피하여 x86 범용 서버와 고속 NVMe-oF 네트워크 상에서 소프트웨어로 스토리지 가상화를 구현하는 클라우드 네이티브 아키텍처.

</details>

- 차세대 하이브리드 클라우드 및 SDDC 환경에서 **SDS(Software-Defined Storage: Ceph, vSAN) 및 NVMe-oF 기반 가상화 표준 채택**

#### 한줄 요약

- **벤더 종속성 탈피와 논리-물리 분리** 활용 통한 동적 스토리지 풀링 최적화
