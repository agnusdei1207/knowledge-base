## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **스토리지 가상화(Storage Virtualization)**: 여러 물리 저장장치의 위치와 차이를 숨기고 통합된 논리 저장공간으로 제공하는 기술이다.
- **논리 저장 계층(Logical Storage Layer)**: 호스트의 블록 주소를 물리 장치 위치로 변환하며 중간에서 I/O를 제어하는 계층이다.
- **이기종 스토리지(Heterogeneous Storage)**: 제조사와 성능 및 접속 방식이 서로 다른 저장장치들의 집합이다.
- **입출력(Input/Output, I/O)**: 호스트와 저장장치 사이에서 데이터를 읽거나 쓰는 작업이다.

</details>

- 정의/개념: **스토리지 가상화**는 **논리 저장 계층**에서 여러 물리 저장장치의 위치와 특성을 숨기고 호스트 **I/O**에 통합된 논리 저장공간을 제공하는 기술이다.
- 배경/필요성: 물리 장치를 개별 관리하면 이기종 용량의 통합 할당과 온라인 이동 및 일관된 보호 정책 적용이 어렵다.

#### 한줄 요약

- **스토리지 가상화**는 **이기종 스토리지**를 통합된 논리 저장공간으로 제공한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **논리•물리 분리(Logical-physical Separation)**: 호스트 주소를 유지하면서 데이터 위치를 독립적으로 변경할 수 있는 성질이다.
- **씬 프로비저닝(Thin Provisioning)**: 논리 용량을 먼저 제공하고 쓰기가 발생할 때 물리 공간을 할당하는 방식이다.
- **온라인 마이그레이션(Online Migration)**: 호스트 서비스를 중단하지 않고 데이터의 물리 저장 위치를 이동하는 기능이다.
- **매핑 계층(Mapping Layer)**: 논리 주소를 물리 위치로 해석하여 모든 I/O 경로에 개입하는 가상화 구성이다.

</details>

- **논리•물리 분리**: **온라인 마이그레이션**을 지원한다.
- **씬 프로비저닝**: 이용률 향상과 용량 고갈 위험이다.
- **매핑 계층** 지연•장애가 전체 I/O 지연•가용성 저하로 전파가 핵심이다.

#### 한줄 요약

- **매핑 계층**의 위치 독립성과 지연•장애 전파 위험이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **논리 볼륨(Logical Volume)**: 서버에 연속된 하나의 블록 장치처럼 보이는 가상 저장공간이다.
- **매핑•제어 엔진(Mapping•Control Engine)**: 주소 해석과 공간 할당, 데이터 이동 및 I/O 완료를 관리하는 구성이다.
- **매핑 메타데이터(Mapping Metadata)**: 논리•물리 위치와 할당 및 이동 상태를 기록한 제어 정보이다.
- **스토리지 풀(Storage Pool)**: 여러 물리 장치의 용량과 보호 수준을 묶어 할당하는 자원 집합이다.

</details>

```text
                         [매핑 메타데이터]
                                  |
                                  |
[논리 볼륨] -- [매핑•제어 엔진] -- [스토리지 풀]
```

선의 의미: 매핑•제어 엔진이 논리 볼륨과 물리 스토리지 풀을 연결하고 별도 매핑 메타데이터와 결합된 정적 가상화 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 논리 볼륨 | 논리 저장공간 제공 |
| 매핑•제어 엔진 | 주소 해석•이동 제어 |
| 매핑 메타데이터 | 논리•물리 관계 보호 |
| 스토리지 풀 | 물리 자원 통합 |

#### 한줄 요약

- **매핑 메타데이터**로 논리 볼륨과 물리 풀을 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **주소 매핑(Address Mapping)**: 호스트의 논리 블록 주소를 스토리지 풀의 저장 위치에 연결하는 정보이다.
- **익스텐트(Extent)**: 연속된 여러 물리 블록을 하나로 묶어 예약하고 할당하는 공간 단위이다.
- **체크섬(Checksum)**: 기록하거나 이동한 데이터에서 계산하여 손상 여부를 확인하는 값이다.
- **원자적 반영(Atomic Commit)**: 매핑 변경 전체가 적용되거나 전혀 적용되지 않은 것처럼 처리하는 성질이다.
- **주소 매핑 조회**: 논리 블록의 기존 물리 위치를 확인하는 단계이다.
- **물리 익스텐트 예약**: 배치 정책을 만족하는 물리 공간을 확보하는 단계이다.
- **데이터·체크섬 기록**: 예약한 위치에 데이터와 무결성 확인값을 저장하는 단계이다.
- **매핑 원자적 확정**: 새 물리 위치를 가리키는 매핑 변경을 한 단위로 반영하는 단계이다.

</details>

```text
[논리 쓰기 요청]
        │
        ▼
1. 주소 매핑 조회
        │
        ▼
2. 물리 익스텐트 예약
        │
        ▼
3. 데이터•체크섬 기록
        │
        ▼
4. 매핑 원자적 확정
        │
        ▼
[논리 I/O 완료 반환]
```

### 동작 원리

1. **주소 매핑 조회**: 논리 블록의 기존 물리 위치를 조회하여 신규 쓰기와 덮어쓰기를 구분한다.
2. **물리 익스텐트 예약**: 용량과 장애 영역 및 배치 정책을 만족하는 물리 공간을 확보한다.
3. **데이터•체크섬 기록**: 예약한 위치에 데이터와 무결성 검사용 체크섬을 기록하고 완료를 확인한다.
4. **매핑 원자적 확정**: 물리 기록이 끝난 뒤 논리 주소가 새 물리 위치를 가리키도록 매핑을 원자적으로 갱신한다.

#### 한줄 요약

- 물리 데이터 기록 후 **원자적 반영**으로 매핑을 확정해야 장애가 발생해도 논리 주소가 미완료 데이터를 가리키지 않는다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **호스트 기반 가상화(Host-based Virtualization)**: 서버 소프트웨어가 직접 여러 저장장치를 통합하여 논리 볼륨을 제공하는 방식이다.
- **네트워크 기반 가상화(Network-based Virtualization)**: 전용 중간 노드가 여러 배열을 공통 풀로 통합하는 방식이다.
- **배열 기반 가상화(Array-based Virtualization)**: 하나의 스토리지 배열 내부 기능으로 물리 디스크를 논리 공간으로 제공하는 방식이다.

</details>

| 가상화 계층 위치 | 호스트 기반 | 네트워크 기반 | 배열 기반 |
|:---|:---|:---|:---|
| 적용 기준 | 소수 서버의 저비용 통합 | 다중 배열의 공통 풀 | 단일 배열의 내장 기능 활용 |
| 핵심 특징 | 호스트 장치 통합 | 전용망 배열 통합 | 배열 내부 통합 |
| 한계 | 호스트 부하 증가 | 중간 노드 병목 | 배열 종속 |

#### 한줄 요약

- 가상화가 포괄해야 하는 서버•배열 범위와 허용 병목에 따라 호스트, 네트워크 또는 배열 기반 방식을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **용량 임계치(Capacity Threshold)**: 물리 여유 공간 부족 전에 할당 제한이나 증설을 시작하는 기준값이다.
- **저널(Journal)**: 메타데이터 변경 순서를 기록하여 장애 후 재실행하는 로그이다.
- **스냅숏(Snapshot)**: 특정 시점의 메타데이터와 데이터 참조 상태를 보존한 복구 기준이다.
- **변경 블록 추적(Changed-block Tracking)**: 마이그레이션 중 새로 변경된 블록을 표시하여 대상 복제본에 다시 반영하는 기능이다.
- **장애 영역(Failure Domain)**: 하나의 제어기나 장치 고장이 동시에 영향을 줄 수 있는 볼륨과 자원의 범위이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 물리 여유 공간이 임계치 아래로 내려 쓰기 중단 위험 | **용량 임계치** 감시와 자동 증설 | 할당 실패 예방 |
| **매핑 메타데이터** 손상으로 **논리 볼륨** 접근 불가 | **저널**과 **스냅숏** 기반 복구 | **주소 매핑** 복구 |
| 이동 중 변경 블록 누락으로 복제본 불일치 | **변경 블록 추적**과 **체크섬** 검증 | **온라인 마이그레이션** 정합성 유지 |
| **매핑•제어 엔진** 장애가 모든 볼륨으로 전파 | 제어 엔진 이중화와 **장애 영역** 분리 | 가용성 유지와 장애 범위 축소 |

#### 한줄 요약

- **변경 블록 추적**으로 서비스 중 온라인 이동 정합성을 유지한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **통합 범위(Integration Scope)**: 가상화 계층이 하나의 서버와 배열 또는 여러 배열 중 어디까지 묶어 관리하는지 나타내는 범위이다.
- **호스트 부하(Host Overhead)**: 서버 CPU와 메모리가 가상화 매핑 및 I/O 처리에 추가로 사용하는 자원이다.
- **배열 종속(Array Lock-in)**: 가상화 기능과 데이터 형식이 특정 스토리지 배열에 의존하여 이전이 어려운 상태이다.
- **가상화 계층 선택 기준**: 통합 범위와 호스트 부하 및 배열 종속을 함께 고려해 가상화 위치를 정하는 기준이다.

</details>

- **가상화 계층 선택 기준**에 따라 **통합 범위**가 소수 서버이고 **호스트 부하**를 허용하면 **호스트 기반 가상화**, 단일 배열에서 **배열 종속**을 허용하면 **배열 기반 가상화**, 여러 배열을 통합하면 **네트워크 기반 가상화**를 선택한다.

#### 한줄 요약

- **통합 범위**와 장애 전파 경계를 기준으로 가상화 계층의 위치를 결정한다.
