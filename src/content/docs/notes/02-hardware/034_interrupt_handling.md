## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: CPU가 명령어를 순차 실행하는 도중 외부 I/O 장치의 비동기 요청이나 내부 예외가 발생했을 때, 현재 실행 문맥을 스택에 보존하고 해당 ISR(인터럽트 서비스 루틴)로 분기하여 처리한 후 복귀하는 하드웨어-소프트웨어 제어 메커니즘.
- **인터럽트 요청(Interrupt Request, IRQ)**: 주변 장치가 하드웨어 신호선 또는 PCIe MSI 메시지를 통해 CPU에 즉각적인 서비스 처리를 요청하는 전기적 신호.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 해당 장치의 데이터를 처리하고 상태 플래그를 클리어하는 커널 핸들러 함수.

</details>

- 정의/개념: 비동기 인터럽트 발생 시 소스를 판별하고 우선순위에 따라 **문맥 보존 ➔ ISR 실행 ➔ 문맥 복원**을 수행하는 **인터럽트 처리(Interrupt Handling) 아키텍처**
- 배경/필요성: 단순 소프트웨어 폴링 방식의 **CPU 자원 낭비 극복 및 다중 주변장치 동시 요청 시 긴급도에 따른 우선순위 제어**

#### 한줄 요약
- 인터럽트 처리는 비동기 이벤트 발생 시 CPU가 문맥을 저장하고 전용 ISR을 실행한 뒤 원래 작업으로 복귀하는 하드웨어 제어 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **문맥 보존(Context Save)**: 현재 실행 중인 프로그램 카운터(PC)와 상태 레지스터(PSR/EFLAGS) 및 범용 레지스터를 프로세스 스택에 안전하게 백업하는 동작.
- **벡터 인터럽트(Vectored Interrupt)**: 인터럽트를 발생시킨 장치가 고유 벡터 번호를 데이터 버스로 공급하여 CPU가 ISR 시작 주소를 직접 조회(Direct Indexing)하는 고속 방식.
- **데이지체인(Daisy Chain)**: 직렬 우선순위 승인선(INTA)을 물리적으로 연결하여 CPU와 가장 가까운 상위 장치가 인터럽트 제어권을 선점하는 하드웨어 구조.

</details>

- 하드웨어 문맥 보존: 인터럽트 진입 시 하드웨어가 자동으로 **PC와 상태 레지스터(PSR)**를 스택에 푸시하여 무손실 복귀 보장
- 소스 판별 고속화: **벡터 인터럽트(Vectored Interrupt)**를 통해 소프트웨어 탐색 없이 1사이클 내에 ISR 시작 주소로 분기
- 하드웨어 우선순위 중재: **데이지체인(Daisy Chain)** 또는 프로그래머블 인터럽트 제어기(APIC)를 통해 다중 IRQ 충돌 시 긴급 장치 우선 처리

#### 한줄 요약
- 벡터 번호로 ISR 분기 시간을 단축하고, 데이지체인이나 APIC로 우선순위를 중재하며, 스택 기반 문맥 보존으로 실행 흐름을 복구한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 벡터 테이블(Interrupt Vector Table, IVT / IDT)**: 인터럽트 벡터 번호를 인덱스로 하여 각 ISR의 시작 주소 포인터를 배열 형태로 저장하는 메모리 테이블.
- **인터럽트 제어기(APIC / PIC)**: 다수의 외부 IRQ 신호를 수신하여 마스킹(Masking), 우선순위 판정 및 CPU 코어로의 라우팅을 총괄하는 하드웨어 제어기.

</details>

```text
[벡터 인터럽트 하드웨어 구조]
 주변장치 군 (NIC, NVMe, 타이머) ──► [인터럽트 제어기 (APIC)] ──► CPU 코어
                                         ├─ 요청 레지스터 (IRR)         │
                                         ├─ 우선순위 판별기 (Priority) ──┼─► [벡터 번호 송출]
                                         └─ 서비스 레지스터 (ISR)       │          │
                                                                       │          ▼
                                                         [메모리: 인터럽트 벡터 테이블 (IVT)]
                                                                       │          │
                                                                       └──────────┼─► [해당 ISR 함수 분기]

[데이지체인 우선순위 직렬 구조]
 CPU (인터럽트 승인선 INTA) ──► [장치 1 (최우선)] ──► [장치 2 (차우선)] ──► [장치 3 (최하위)]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; APIC는 병렬 우선순위를 판정하고 데이지체인은 직렬 승인 신호를 전파함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **인터럽트 제어기 (APIC)**| CPU 다이 및 칩셋 | 다중 IRQ 수신, 우선순위 판정, 멀티코어 인터럽트 분산 | MSI-X 메시지 인터럽트 지원 |
| **인터럽트 벡터 테이블 (IVT)**| 시스템 DRAM (커널 메모리)| 벡터 번호와 **ISR 시작 함수 주소 매핑** 보관 | IDTR 레지스터가 베이스 가리킴 |
| **인터럽트 서비스 루틴 (ISR)**| OS 커널 디바이스 드라이버| 장치 데이터 처리 및 인터럽트 플래그 클리어 | Top-half / Bottom-half 분리 |
| **문맥 보존 스택** | 프로세스 / 커널 스택 | 인터럽트 발생 전 PC, PSR, 범용 레지스터 안전 백업 | IRET 명령어로 원자적 복원 |

#### 한줄 요약
- 인터럽트 시스템은 APIC 제어기, 인터럽트 벡터 테이블(IVT), 드라이버 ISR, 문맥 보존 스택으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IRET(Interrupt Return)**: 스택에 보존되었던 PC와 플래그 레지스터를 복원하여 인터럽트 발생 전 명령어로 실행 흐름을 원자적으로 되돌리는 명령어.

</details>

```text
1. 주변장치에서 인터럽트 요청(IRQ) 발생
                      │
                      ▼
2. 인터럽트 제어기(APIC): 마스크 확인 및 우선순위 판정
                      │
                      ▼
3. CPU 코어: 현재 실행 중인 기계어 명령어 완료 후 인터럽트 수락 (INTA)
                      │
                      ▼
4. 하드웨어 문맥 보존: PC(Program Counter)와 PSR(상태 레지스터)를 스택에 Push
                      │
                      ▼
5. 벡터 번호 인출 ➔ 인터럽트 벡터 테이블(IVT) 조회 ➔ 해당 ISR 시작 주소로 분기
                      │
                      ▼
6. ISR 실행 (장치 I/O 데이터 처리 및 인터럽트 플래그 클리어)
                      │
                      ▼
7. IRET 명령어 실행: 스택에서 이전 PC 및 PSR 복원 ➔ 중단되었던 프로그램 원상 복구 재개
```

분기 결과: **우선순위가 높은 인터럽트는** 현재 작업을 중단하고 즉시 ISR로 진입하며, **완료 후에는** IRET를 통해 중단 지점으로 100% 안전 복구됨

#### 한줄 요약
- IRQ 발생 ➔ APIC 판정 ➔ CPU 수락 ➔ 문맥 스택 저장 ➔ IVT 조회 및 ISR 실행 ➔ IRET 문맥 복원의 7단계로 동작한다.

## Ⅴ. 종류 및 비교

| 인터럽트 판별 방식 | 벡터 인터럽트 (Vectored) | 비벡터 인터럽트 (Non-Vectored) | 데이지체인 (Daisy Chain) | 소프트웨어 폴링 (Polling) |
|:---|:---|:---|:---|:---|
| 판별 주체 | **하드웨어 (장치가 벡터 번호 송출)** | 소프트웨어 (고정 시작점에서 탐색) | **하드웨어 (직렬 INTA 승인선 전파)** | 소프트웨어 (CPU가 상태 레지스터 루프) |
| 소스 식별 지연 | **초고속 (1클록 내 IVT 직접 조회)** | 느림 (모든 장치 상태 순차 검사) | 빠름 (물리 신호 전파 지연만 존재) | 매우 느림 (장치 수에 비례하여 증가) |
| 우선순위 결정 방식| **APIC 레지스터 프로그래밍** | 소프트웨어 if-else 검사 순서 | **물리적 배선 연결 순서 (고정)** | 소프트웨어 폴링 루프 순서 |
| 하드웨어 비용 | 중간 (인터럽트 제어기 필요) | 매우 낮음 | 낮음 (직렬 승인선 배선) | 0 (추가 하드웨어 불필요) |
| 주요 적용 분야 | **현대 멀티코어 x86/ARM 시스템 (APIC)** | 단순 레거시 8비트 MCU | 산업용 VME 버스, 구형 임베디드 | 초단순 센서 제어 루프 |

#### 한줄 요약
- 현대 고성능 시스템은 APIC 기반 벡터 인터럽트가 표준이며, 단순 배선에는 데이지체인이, 초단순 시스템에는 소프트웨어 폴링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Top-half / Bottom-half**: 긴급한 하드웨어 ACK 처리는 상반부(Top-half)에서 즉시 끝내고, 무거운 데이터 처리는 하반부(Bottom-half / SoftIRQ)로 지연 처리하는 기법.
- **인터럽트 네스팅(Interrupt Nesting)**: ISR 실행 중 더 높은 우선순위 인터럽트의 중첩 진입을 허용하는 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISR 내부 처리 지연으로 타 고우선순위 인터럽트 차단 | **Top-half(하드웨어 ISR) / Bottom-half(SoftIRQ/Tasklet) 분리** | ISR 실행 시간을 수 $\mu\text{s}$ 이내로 단축 및 시스템 응답성 보장 |
| 특정 장치의 인터럽트 독점으로 저우선순위 장치 기아(Starvation) | **회전 우선순위(Rotating Priority) 및 인터럽트 완화** | 장치 간 공정한 처리 기회 보장 |
| 과도한 **인터럽트 네스팅(Nesting)**으로 커널 스택 오버플로 | **중첩 깊이 제한 및 전용 독립 인터럽트 스택(Interrupt Stack) 할당** | 커널 패닉 방지 및 시스템 안정성 확보 |

#### 한줄 요약
- 실무에서는 Top-half/Bottom-half 분리로 ISR 지연을 최소화하고, 독립 인터럽트 스택으로 중첩 오버플로를 방지한다.

## Ⅶ. 결론

- 멀티코어 환경의 고속 비동기 이벤트 처리를 위해 **APIC 제어기와 MSI-X 기반의 벡터 인터럽트(Vectored Interrupt) 구조를 표준 채택**하고, 커널 응답성을 극대화하기 위해 **Top-half/Bottom-half 분리 드라이버 구조**를 적용하며, 인터럽트 폭주 방지를 위해 **인터럽트 완화(Coalescing) 및 독립 스택 관리 기술**을 융합하는 고신뢰 실시간 인터럽트 처리 시스템 구축

#### 한줄 요약
- 인터럽트 처리는 APIC 벡터 구조와 Top-half/Bottom-half 분리를 통해 초저지연과 시스템 안정성을 동시에 달성한다.
