## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **인터럽트 처리(Interrupt Handling)**: 비동기 요청으로 실행을 전환해 원인을 처리한 뒤 이전 문맥으로 복귀하는 절차.
- **IRQ(Interrupt Request)**: 장치나 타이머가 CPU에 비동기 처리를 요구하는 신호.
- **CPU(Central Processing Unit)**: 프로그램 명령을 실행하는 장치.

</details>

- 정의/개념: 비동기 요청을 중재해 해당 처리 루틴으로 실행을 전환하고 이전 문맥으로 복귀하는 **인터럽트 처리** 절차
- 배경/필요성: CPU가 주변장치의 입출력 준비 상태를 주기적으로 조회하는 폴링 방식은 CPU 유휴 시간 오버헤드 유발

#### 한줄 요약

- 인터럽트가 발생하면 제어기가 요청을 중재하고 CPU가 문맥 저장, ISR 실행, 원인 해제, 문맥 복원 순서로 처리한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **ISR(Interrupt Service Routine)**: 인터럽트 원인의 긴급 처리를 수행하는 코드.
- **인터럽트 지연(Interrupt Latency)**: 요청이 발생한 시점부터 ISR 실행이 시작될 때까지 걸리는 시간.
- **중첩 인터럽트(Nested Interrupt)**: ISR 실행 중 더 높은 우선순위 요청의 진입을 허용하는 방식.
- **실행 흐름 전환(Execution Flow Transfer)**: 현재 명령 실행을 멈추고 ISR 진입 주소로 CPU 제어를 옮기는 동작.

</details>

- 명령 경계에서 **실행 흐름 전환** 후 ISR 진입
- 마스킹•우선순위•문맥 저장에 따라 달라지는 **인터럽트 지연**
- 고우선 지연 감소와 문맥 비용 증가를 만드는 **중첩 인터럽트**

#### 한줄 요약

- 우선순위와 중첩 인터럽트는 긴급 요청의 대기 시간을 줄이지만 문맥 저장 횟수와 스택 사용량을 증가시킨다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **인터럽트 제어기(Interrupt Controller)**: 마스킹•우선순위 중재 후 대상 CPU에 IRQ를 전달하는 하드웨어.
- **인터럽트 벡터(Interrupt Vector)**: 원인별 ISR을 식별하는 번호.
- **인터럽트 벡터 테이블(Interrupt Vector Table)**: 인터럽트 벡터별 ISR 진입 주소를 저장한 표.
- **실행 문맥(Execution Context)**: 인터럽트 복귀를 위해 저장하는 프로그램 카운터•레지스터•상태 정보.

</details>

```text
[IRQ 원천] -- [인터럽트 제어기] -- [벡터•체인 식별 경로]
                                            |
                                      [CPU•ISR 문맥]
```

선의 의미: IRQ 원천과 중재 제어기, 원인 식별 경로, CPU의 ISR 문맥을 잇는 정적 하드웨어•문맥 인터페이스 관계.

| 구성요소 | 책임 |
|:---|:---|
| IRQ 원천 | 장치•타이머의 비동기 요청 발생 |
| 인터럽트 제어기 | 마스크•우선순위 기반 요청 중재 |
| 벡터•체인 식별 경로 | 벡터•승인 순서로 원인 식별 |
| CPU•ISR 문맥 | 문맥 저장•원인 처리•복귀 |

#### 한줄 요약

- 제어기가 요청을 고르고 식별 경로가 ISR을 찾으면 CPU가 문맥을 저장하고 처리한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **마스킹(Masking)**: 특정 인터럽트 요청의 CPU 전달을 차단하는 제어.
- **중재(Arbitration)**: 여러 IRQ 중 처리할 하나를 우선순위로 선택하는 제어.
- **EOI(End of Interrupt)**: ISR 완료를 제어기에 알리는 신호.
- **원인 해제(Source Clear)**: 장치의 완료•오류 상태를 확인하고 IRQ가 다시 발생하지 않도록 상태를 정리하는 동작.

</details>

```text
                         [IRQ 발생]
                             |
                   1. 마스크•우선순위 중재
                             |
                  2. 문맥 저장•ISR 주소 식별
                             |
                         [ISR 진입]
                             |
                3. 원인 처리•해제•EOI 전달
                             |
                    4. 문맥 복원•복귀
                             |
                     [중단 실행 재개]
```

### 동작 원리

1. **마스크·우선순위 중재**: 허용된 IRQ 가운데 우선순위가 가장 높은 요청을 CPU 전달 대상으로 선택.
2. **문맥 저장·ISR 식별**: 복귀할 프로그램 상태를 저장하고 **인터럽트 벡터** 또는 승인 경로로 ISR 주소 확인.
3. **원인 처리·해제·EOI 전달**: 장치의 완료·오류 상태를 처리해 IRQ **원인 해제**하고 제어기에 **EOI** 통지.
4. **문맥 복원·복귀**: 저장한 프로그램 카운터와 레지스터 상태를 복원해 중단된 실행 재개.

#### 한줄 요약

- 제어기가 IRQ를 중재하면 CPU는 복귀 문맥을 저장하고 ISR에서 원인을 해제한 뒤 이전 실행 상태를 복원한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **벡터 방식(Vectored Interrupt)**: 인터럽트 번호로 ISR 주소를 직접 찾아 원인을 식별하는 방식.
- **데이지체인(Daisy Chain)**: 승인 신호를 장치 연결 순서대로 전달해 요청자와 고정 우선순위를 찾는 방식.
- **기아(Starvation)**: 낮은 우선순위 요청이 높은 요청에 계속 밀려 처리되지 못하는 상태.

</details>

| 인터럽트 식별 방식 | 벡터 | 데이지체인 |
|:---|:---|:---|
| 적용 기준 | 인터럽트 원인이 많아 빠른 원인 식별 필요 시 | 소수 장치에 고정 순위 적용 시 |
| 핵심 특징 | ISR을 직접 식별하는 **인터럽트 벡터** | 요청자•순위를 찾는 직렬 승인 |
| 한계 | **인터럽트 벡터 테이블**•제어기 복잡도 | 전파 지연•**기아**•연쇄 장애 |

#### 한줄 요약

- 다수 원인을 빠르게 식별하려면 벡터 방식을, 소수 장치의 고정 우선순위를 단순하게 구현하려면 데이지체인을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **지연 처리(Deferred Processing)**: ISR에서는 원인만 해제하고 긴 작업을 별도 커널 작업으로 넘기는 방식.
- **우선순위 노화(Priority Aging)**: 오래 기다린 낮은 우선순위 요청의 순위를 점차 높여 기아를 막는 방법.
- **MSI-X(Message Signaled Interrupts eXtended)**: 메시지 기반 다중 인터럽트 방식.
- **MSI-X 벡터 친화도(MSI-X Vector Affinity)**: 독립 벡터를 담당 큐와 CPU에 배정하는 정책.
- **NVMe(Non-Volatile Memory Express)**: 멀티큐별 MSI-X 벡터를 사용할 수 있는 저장장치 인터페이스.
- **처리 예산(Processing Budget)**: 한 우선순위나 요청 집합이 연속으로 사용할 수 있는 CPU 처리량의 한도.
- **중첩 깊이 제한(Nesting Depth Limit)**: 동시에 쌓을 수 있는 중첩 인터럽트 단계 수를 제한하는 정책.
- **인터럽트 폭주(Interrupt Storm)**: 과도한 완료 통지가 특정 CPU를 인터럽트 처리에 묶는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISR이 긴 작업을 수행해 낮은 우선순위 인터럽트 지연 | 원인만 해제한 뒤 긴 작업을 **지연 처리**로 이관 | ISR 점유 시간 감소로 후속 인터럽트 지연 단축 |
| 고정 우선순위 요청이 계속 도착해 **기아** 발생 | **우선순위 노화**·**처리 예산**과 요청별 처리율 감시 | 대기 시간 상한 확보로 처리 공정성 향상 |
| 인터럽트 중첩이 깊어져 스택·문맥 저장 공간 고갈 | **중첩 깊이 제한**과 전용 인터럽트 스택 적용 | 문맥 자원 한도 유지로 실행 안정성 확보 |
| 완료 통지가 특정 코어에 몰려 **인터럽트 폭주** | 인터럽트 병합과 **MSI-X 벡터 친화도** 적용 | 코어별 부하 분산으로 완료 처리량 안정화 |

> 사례: **NVMe** 멀티큐는 **MSI-X** 벡터를 큐•CPU에 배정

#### 한줄 요약

- ISR은 장치 원인 해제와 긴급 상태만 처리하고, 시간이 오래 걸리는 작업은 지연 처리로 이관한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **인터럽트 식별 방식 선택 기준**: 원인 수·허용 식별 지연·배선 복잡도로 벡터와 데이지체인을 고르는 기준.

</details>

- **인터럽트 식별 방식 선택 기준**에 따라 다수 원인의 빠른 식별에는 **벡터 방식**, 소수 장치의 고정 순위에는 **데이지체인** 선택

#### 한줄 요약

- 인터럽트 원인 수, 허용 식별 지연, 배선·제어기 복잡도를 기준으로 벡터 또는 데이지체인 방식을 선택한다.
