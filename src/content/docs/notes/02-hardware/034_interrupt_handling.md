## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: CPU가 명령을 실행하는 도중 외부 장치 또는 내부 예외가 발생했을 때, 현재 문맥(Context)을 보존하고 전용 ISR을 실행한 후 복귀하는 제어 메커니즘.
- **인터럽트 요청(IRQ)**: 주변 장치가 하드웨어 핀이나 메시지(MSI)를 통해 CPU에 즉각적인 처리를 요청하는 전기적 신호.
- **인터럽트 서비스 루틴(ISR)**: 해당 인터럽트를 전담하여 장치의 I/O 데이터를 인출하고 상태를 처리하는 커널 함수.

</details>

- 정의/개념: 비동기적 하드웨어 및 소프트웨어 이벤트 발생 시, CPU가 현재 실행 문맥(Context)을 보존하고 해당 인터럽트 서비스 루틴(ISR)을 실행한 후 복귀하는 제어 메커니즘
- 배경/필요성: CPU의 주기적인 폴링(Polling) 오버헤드를 제거하고, **입출력 장치 완료 및 시스템 비상 예외 상황에 즉각적·비동기적으로 반응**

#### 한줄 요약

- 하드웨어 이벤트 발생 시 **문맥 저장 $\to$ ISR 실행 $\to$ 문맥 복원**을 수행하는 비동기 제어

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인터럽트 지연(Interrupt Latency)**: 하드웨어 요청 신호 발생 시점부터 ISR의 첫 번째 명령어가 실행되기 직전까지 소요되는 지연시간.
- **중첩 인터럽트(Nested Interrupt)**: 실행 중인 ISR보다 더 높은 우선순위의 인터럽트가 발생했을 때 기존 처리를 일시 중단하고 우선 선점하는 방식.
- **문맥 교환(Context Save/Restore)**: PC, SP, 상태 레지스터(FLAGS) 및 범용 레지스터를 커널 스택에 푸시하고 복귀 시 팝하는 동작.

</details>

- 하드웨어적 우선순위 판정과 인터럽트 마스크(IMR) 검사를 통한 신속한 제어 흐름 전환
- 전용 하드웨어 인터럽트 컨트롤러(PIC, APIC, NVIC, GIC)를 통한 다중 장치 동시 요청의 우선순위 중재
- 긴급한 요청 처리를 위한 **중첩 인터럽트(Nesting)** 지원 및 이에 따른 커널 스택 깊이 관리 수반

#### 한줄 요약

- **우선순위 판정·문맥 보존(Context Switch)·중첩 인터럽트(Nesting)** 지원

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 컨트롤러(Interrupt Controller)**: 장치들의 IRQ 라인을 취합하여 우선순위를 중재하고 승리한 장치의 벡터 번호를 CPU에 전달하는 하드웨어 (Intel APIC, ARM GIC).
- **인터럽트 벡터 테이블(IVT / IDT)**: 각 벡터 번호에 대응하는 ISR의 시작 물리/가상 주소를 매핑해 둔 메모리 상의 함수 포인터 배열.

</details>

```text
[ 인터럽트 컨트롤러 및 벡터 테이블 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 주변 입출력 장치 (타이머, 키보드, NVMe SSD, NIC)           │
│  └─ 개별 하드웨어 IRQ 라인 (IRQ 0 ~ IRQ N)                  │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 인터럽트 컨트롤러 (Intel APIC / ARM GIC / ARM NVIC)         │
│  ├─ 우선순위 판정 로직 (Priority Arbiter) 및 마스크(IMR)     │
│  └─ 승리한 장치의 인터럽트 벡터 번호(Vector #) 송출         │
└──────────────────────────────┬──────────────────────────────┘
                               │ (INTR 신호 + Vector #)
┌──────────────────────────────┴──────────────────────────────┐
│ 중앙처리장치 코어 (CPU Core)                                 │
│  ├─ 현재 PC / SP / Register 스택에 Push (문맥 저장)          │
│  ├─ 인터럽트 벡터 테이블(IVT / IDT) 조회 ──> ISR 주소 획득   │
│  └─ 해당 ISR로 점프하여 실행 후 EOI 전송 및 스택 Pop 복귀   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 주변 장치 요청 신호(IRQ), 인터럽트 컨트롤러(APIC/NVIC), CPU 코어 및 인터럽트 벡터 테이블(IVT) 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 제어기 | 무수히 쏟아지는 개별 요청의 마스킹, 우선순위 판정 및 물리적 코어 라우팅 제어 총괄 |
| 인터럽트 벡터 | 중앙처리장치가 즉각 처리해야 할 대상 장치의 고유 색인 식별 번호 직접 제공 |
| 인터럽트 벡터 테이블 | 고유 벡터 번호별로 지정된 운영체제 커널 서비스 루틴의 시작 메모리 물리 주소 영구 보관 |
| 인터럽트 종료 신호 (EOI) | 제어기에 현재 서비스 루틴 처리 완료 및 다음 대기 중인 인터럽트 수신 허용 명시적 통지 |

#### 한줄 요약

- **인터럽트 컨트롤러(중재)·벡터 번호(식별)·벡터 테이블(IVT)·EOI 신호** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Top-Half / Bottom-Half**: ISR의 앞부분(Top-Half)은 하드웨어 Ack 및 큐잉만 1$\mu$s 내에 신속 처리하고, 무거운 데이터 처리는 소프트웨어 인터럽트(Bottom-Half, SoftIRQ, Tasklet, Workqueue)로 위임하는 기법.

</details>

```text
[ 주변 장치 IRQ 인터럽트 요청 발생 ]
                 │
                 ▼
[ 1. 인터럽트 컨트롤러 우선순위 판정 및 Vector 번호 CPU 전달 ]
                 │
                 ▼
[ 2. CPU 파이프라인 중단 및 현재 레지스터 문맥 스택 저장 ]
                 │
                 ▼
[ 3. IVT 조회 후 해당 ISR(Top-Half) 즉시 점프 실행 ]
                 │
      [ 무거운 후속 처리 필요 여부 ]
                 │
       ┌─────────┴─────────┐
       ▼ [단순 I/O]        ▼ [대량 데이터 패킷 등]
 [ 4-A. 즉시 처리 ]   [ 4-B. Bottom-Half(SoftIRQ) 작업 큐 등록 ]
       │                   │
       └─────────┬─────────┘
                 ▼
[ 5. 인터럽트 컨트롤러에 EOI(End of Interrupt) 송신 ]
                 │
                 ▼
[ 6. 스택에서 문맥 복원(IRET) 후 원래 프로그램 복귀 ]
```

**동작 원리**

1. **중재 및 전송**: 인터럽트 컨트롤러가 우선순위를 판정하여 승리한 장치의 벡터 번호를 CPU에 전달
2. **문맥 저장**: CPU가 현재 실행 중인 프로그램의 PC, FLAGS 및 레지스터를 스택에 자동 저장
3. **ISR 실행**: IVT에서 벡터 번호에 매핑된 ISR 주소를 읽어 점프한 후 장치 원인 레지스터 해제(Top-Half)
4. **지연 처리 및 복구**: 무거운 패킷 처리는 SoftIRQ(Bottom-Half)에 등록하고, EOI 신호 전송 후 `IRET` 명령으로 본래 작업 복귀

#### 한줄 요약

- IRQ 발생 $\to$ **우선순위 중재 $\to$ 문맥 스택 저장 $\to$ Top-Half/Bottom-Half 처리 $\to$ EOI 및 복귀**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Vectored vs Daisy Chain vs Polled**:
  - Vectored: 하드웨어가 직접 고유 벡터 번호를 제공하여 즉시 분기 (현대 표준)
  - Daisy Chain: 직렬 우선순위 전파 라인(Ack)을 타고 가까운 장치가 먼저 신호 가로챔
  - Polled: CPU가 단일 인터럽트 선 수신 후 모든 장치 상태를 소프트웨어 루프로 검사

</details>

| 비교 항목 | 벡터 인터럽트 (Vectored) | 데이지 체인 (Daisy Chain) | 폴링 인터럽트 (Polled) |
|:---|:---|:---|:---|
| 장치 식별 및 우선순위 | 장치가 데이터 버스로 고유 벡터 번호 직접 전송 | 직렬 Ack 신호 전파 순서(물리적 근접도)로 결정 | CPU가 모든 장치의 상태 레지스터를 순차 소프트웨어 검사 |
| 식별 지연 및 확장성 | IVT 직접 룩업으로 지연 극소화 및 고속 확장 | 체인 통과 지연 발생, 하위 장치 기아 위험 | 장치 수 증가 시 O(N) 지연시간 급증 |
| 한계 및 하드웨어 비용 | 전용 인터럽트 컨트롤러 및 버스 배선 비용 증가 | 체인 중간 장치 고장 시 하위 전체 마비 | CPU 연산 자원 낭비 심각 (Busy Wait) |

#### 한줄 요약

- 벡터 방식은 **고성능 저지연 표준**, 데이지체인은 **하드웨어 단순성**, 폴링은 **소프트웨어 구현**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Interrupt Affinity(smp_affinity)**: 멀티코어 환경에서 특정 고속 I/O 장치(100GbE NIC 등)의 인터럽트를 특정 CPU 코어에 고정 바인딩하여 캐시 미스와 코어 간 핑퐁을 방지하는 설정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서비스 루틴 코드가 무겁고 길어져 시스템 전체의 다른 인터럽트가 영구적으로 무한 대기 지연되는 현상 발생 | **상반부 및 하반부 분리**를 통한 무거운 작업의 백그라운드 지연 큐 적극적 위임 아키텍처 도입 | 서비스 루틴의 실제 코어 점유 실행 시간을 마이크로초 단위로 극소화 및 시스템 전반의 반응성 100% 확보 |
| 고장 난 불량 하드웨어 디바이스에서 의미 없는 요청 신호가 초당 수십만 번씩 끊임없이 터져 나오는 폭주 현상 | 운영체제 커널 차원의 다중 인터럽트 병합 기술 튜닝 및 임계치 초과 시 장애 장치 영구 비활성화 | 프로세서 코어 마비 현상 및 자원 고갈 원천 차단 및 무중단 서버 시스템 구동 안정성 확보 보장 |
| 멀티코어 환경에서 방대한 입출력 요청 신호가 단일 0번 코어로만 가혹하게 집중되어 병목과 부하 불균형 초래 | **인터럽트 친화도** 마스크 강제 바인딩 튜닝 및 동적 부하 분산 스케줄링 데몬 백그라운드 구동 | 다중 코어 간의 입출력 인터럽트 처리 부하를 완벽히 균등 분산시키고 전체 시스템 처리 대역폭 극대화 |
| 잦은 중첩 인터럽트로 인해 스택 호출 깊이가 걷잡을 수 없이 깊어져 한정된 커널 스택 메모리가 붕괴됨 | 커널 및 펌웨어 레벨의 중첩 호출 깊이 강제 제한 설정 및 인터럽트 처리를 위한 전용 독립 스택 공간 분리 할당 | 커널 스택 메모리 꼬리 파손 및 그로 인한 치명적인 시스템 전체 크래시 현상 물리적 사전 예방 |

#### 한줄 요약

- **Top-Half/Bottom-Half 분리·인터럽트 친화도(smp_affinity)·독립 IRQ 스택**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **MSI / MSI-X (Message Signaled Interrupts)**: 물리적 핀 배선 대신 PCIe 메모리 쓰기 트랜잭션 패킷을 통해 멀티코어로 직접 인터럽트를 라우팅하는 최신 고속 인터럽트 표준.

</details>

- 멀티코어 서버 및 고성능 SoC 환경에서 **APIC/GIC 기반 벡터 인터럽트 및 MSI-X 메시지 인터럽트 표준 채택**

#### 한줄 요약

- **벡터 방식 기반 저지연 처리와 상/하반부 커널 분리**를 통한 반응성 극대화
