## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: CPU가 명령어를 순차 실행하는 도중 외부 I/O 장치의 비동기 요청이나 내부 예외가 발생했을 때, 현재 실행 문맥을 스택에 보존하고 해당 ISR(인터럽트 서비스 루틴)로 분기하여 처리한 후 복귀하는 하드웨어-소프트웨어 제어 메커니즘.
- **인터럽트 요청(Interrupt Request, IRQ)**: 주변 장치가 하드웨어 신호선 또는 PCIe MSI 메시지를 통해 CPU에 즉각적인 서비스 처리를 요청하는 전기적 신호.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 해당 장치의 데이터를 처리하고 상태 플래그를 클리어하는 커널 핸들러 함수.

</details>

- 정의/개념: CPU 명령어 실행 중 비동기적 I/O 요청이나 예외 발생 시 현재 문맥을 보존하고 해당 ISR(인터럽트 서비스 루틴)로 분기하여 긴급 작업을 처리하는 **하드웨어-소프트웨어 제어 체계**
- 배경/필요성: 주기적 폴링에 따른 CPU 연산 자원 낭비(Busy Waiting) 제거 및 외부 비동기 사건에 대한 초저지연 식별과 우선순위 기반 선점 처리 실현

#### 한줄 요약
- 인터럽트 처리는 비동기 이벤트 발생 시 CPU가 문맥을 저장하고 전용 ISR을 실행한 뒤 원래 작업으로 복귀하는 하드웨어 제어 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **문맥 보존(Context Save)**: 현재 실행 중인 프로그램 카운터(PC)와 상태 레지스터(PSR/EFLAGS) 및 범용 레지스터를 프로세스 스택에 안전하게 백업하는 동작.
- **벡터 인터럽트(Vectored Interrupt)**: 인터럽트를 발생시킨 장치가 고유 벡터 번호를 데이터 버스로 공급하여 CPU가 ISR 시작 주소를 직접 조회(Direct Indexing)하는 고속 방식.
- **데이지체인(Daisy Chain)**: 직렬 우선순위 승인선(INTA)을 물리적으로 연결하여 CPU와 가장 가까운 상위 장치가 인터럽트 제어권을 선점하는 하드웨어 구조.

</details>

- 인터럽트 발생 시 하드웨어가 자동으로 **프로그램 카운터(PC)와 상태 레지스터(PSR)**를 스택에 대피시켜 무손실 복구 보장
- **벡터 인터럽트(Vectored Interrupt)**를 통해 소프트웨어 조건 탐색 없이 1사이클 내에 해당 ISR 시작 주소로 직결 분기
- **데이지체인 및 프로그래머블 인터럽트 제어기(APIC)**를 활용하여 복수 IRQ 동시 발생 시 우선순위 하드웨어 중재

#### 한줄 요약
- 벡터 번호로 ISR 분기 시간을 단축하고, 데이지체인이나 APIC로 우선순위를 중재하며, 스택 기반 문맥 보존으로 실행 흐름을 복구한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 벡터 테이블(Interrupt Vector Table, IVT / IDT)**: 인터럽트 벡터 번호를 인덱스로 하여 각 ISR의 시작 주소 포인터를 배열 형태로 저장하는 메모리 테이블.
- **인터럽트 제어기(APIC / PIC)**: 다수의 외부 IRQ 신호를 수신하여 마스킹(Masking), 우선순위 판정 및 CPU 코어로의 라우팅을 총괄하는 하드웨어 제어기.

</details>

```text
[인터럽트 제어 및 처리 체계]
  │
  ├─ [주변 장치 군] (I/O Device Array)
  │     ├─ [IRQ 발생기] (하드웨어 핀 또는 MSI-X 패킷)
  │     └─ [데이지체인 단자] (직렬 INTA 승인선 연결)
  │
  ├─ [인터럽트 제어기] (APIC / PIC)
  │     ├─ [요청/마스크 레지스터] (IRR, IMR 상태 관리)
  │     ├─ [우선순위 판별 로직] (PR, 최고 순위 선점 중재)
  │     └─ [서비스 중 레지스터] (ISR, 현재 처리 인터럽트 추적)
  │
  └─ [호스트 프로세서] (CPU Core 및 OS 커널)
        ├─ [문맥 보존 스택] (PC, 플래그 자동 대피/복원)
        ├─ [인터럽트 벡터 테이블] (IVT / IDT, 핸들러 분기)
        └─ [인터럽트 서비스 루틴] (Top-half 즉시 제어 및 Bottom-half)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 제어기 (APIC) | 복수 IRQ의 우선순위 판정, **마스킹 제어 및 코어별 벡터 라우팅** |
| 인터럽트 벡터 테이블 (IVT) | 벡터 번호를 인덱스로 하여 **해당 ISR 시작 주소 포인터 보관** |
| 인터럽트 서비스 루틴 (ISR) | 긴급 장치 제어(Top-half) 및 **지연된 데이터 처리(Bottom-half) 수행** |
| 문맥 보존 스택 | 인터럽트 진입 시 PC·PSR 레지스터를 백업하고 **IRET 복귀 보장** |

#### 한줄 요약
- 인터럽트 제어기가 CPU 앞단에서 우선순위 판정을 대신해 장치 상태를 주기적으로 확인하는 폴링 루프를 없애고, 인터럽트 벡터 테이블이 ISR 주소 탐색을 벡터 번호 인덱싱 한 번으로 대신하므로 소프트웨어 소스 판별 과정이 사라진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IRET(Interrupt Return)**: 스택에 보존되었던 PC와 플래그 레지스터를 복원하여 인터럽트 발생 전 명령어로 실행 흐름을 원자적으로 되돌리는 명령어.

</details>

```text
주변 장치          APIC(제어기)           CPU            스택·IVT
   │                 │                 │                 │
   │────────────────>│ IRQ 신호 인가   │                 │
   │                 │ 1. 우선순위 중재│                 │
   │                 │────────────────>│ INTR 신호 전달  │
   │                 │<────────────────│ 2. INTA 수락    │
   │                 │                 │────────────────>│
   │                 │                 │ 3. 문맥 보존 (Push)
   │                 │                 │<────────────────│
   │                 │                 │ 4. IVT 벡터 조회│
   │                 │                 │                 │
   │                 │                 │ 5. ISR 실행 및 IRET
```

분기 결과: **마스크 불가 인터럽트(NMI) 및 고순위 IRQ**는 즉시 CPU를 선점하여 ISR로 진입하나, **마스킹된 저순위 IRQ**는 대기 큐에 보류되어 상위 작업 완료 시까지 처리 지연됨

**동작 원리**

1. **우선순위 중재**: 외부 장치가 IRQ를 인가하면 인터럽트 제어기가 IMR 마스크 여부를 검사하고 다중 요청 중 가장 우선순위가 높은 장치 선정
2. **INTA 수락**: CPU가 현재 실행 중인 단일 기계어 명령어 사이클을 완료한 즉시 인터럽트 승인 신호(INTA)를 제어기로 반환
3. **문맥 보존**: CPU 하드웨어가 현재 실행 중인 프로그램 카운터(PC)와 프로세서 상태 레지스터(PSR)를 커널 스택에 자동 저장(Push)
4. **IVT 벡터 조회**: 데이터 버스로 수신된 고유 벡터 번호로 인터럽트 벡터 테이블(IVT)을 인덱싱하여 해당 ISR 시작 주소 직접 인출
5. **ISR 실행 및 IRET**: Top-half 핸들러가 장치 데이터를 수신하고 인터럽트 플래그를 해제한 후, IRET 명령어로 스택 문맥을 복원하여 이전 코드로 복귀

#### 한줄 요약
- 이 경로는 장치가 실제로 준비됐을 때만 열리므로 상태를 계속 되묻던 폴링 소모가 사라지지만, 열리는 시점을 예측할 수 없어 그때 실행 중이던 작업이 문맥 저장과 복원 비용을 대신 떠안는다.

## Ⅴ. 종류 및 비교

| 인터럽트 판별 방식 | 벡터 인터럽트 (Vectored) | 데이지체인 (Daisy Chain) | 비벡터 인터럽트 (Non-Vectored) | 소프트웨어 폴링 (Polling) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초고속 식별 및 최신 멀티코어 서버 환경 | 단순 직렬 하드웨어 우선순위 중재 요구 시 | 단일 ISR 진입점 중심 레거시 임베디드 MCU | 초단순 센서 및 전용 인터럽트 회로 부재 시스템 |
| 핵심 특징 | 장치가 송출한 **고유 벡터 번호**로 IVT를 1사이클 내 직접 인덱싱 | 직렬 **INTA 승인선** 기반 하드웨어 캐스케이딩 우선순위 선점 | 단일 시작점으로 분기 후 **소프트웨어 조건문**으로 장치 식별 | CPU 루프에서 장치별 **상태 레지스터 플래그** 순차 검사 |
| 한계 | 전용 **APIC/MSI 제어 회로** 탑재로 하드웨어 복잡도 증가 | 체인 후순위 장치의 **신호 전파 지연** 및 물리 배선 종속성 | 소프트웨어 장치 판별 루프로 인한 **지연 시간 증가** | 장치 수에 비례한 탐색 지연 및 **CPU 연산 극심한 낭비** |

#### 한줄 요약
- 현대 고성능 시스템은 APIC 기반 벡터 인터럽트가 표준이며, 단순 배선에는 데이지체인이, 초단순 시스템에는 소프트웨어 폴링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Top-half / Bottom-half**: 긴급한 하드웨어 ACK 처리는 상반부(Top-half)에서 즉시 끝내고, 무거운 데이터 처리는 하반부(Bottom-half / SoftIRQ)로 지연 처리하는 기법.
- **인터럽트 네스팅(Interrupt Nesting)**: ISR 실행 중 더 높은 우선순위 인터럽트의 중첩 진입을 허용하는 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 긴 ISR 실행 시간으로 인한 후속 인터럽트 유실 및 블로킹 | **Top-half / Bottom-half(SoftIRQ)** 분리 처리 | 하드웨어 응답 시간 극소화 및 지연 처리 보장 |
| 특정 고빈도 장치의 독점으로 인한 저순위 장치 기아 현상 | **회전 우선순위(Rotating Priority)** 및 완화 적용 | 모든 인터럽트 소스에 공정한 처리 기회 보장 |
| 인터럽트 중첩 심화에 따른 커널 스택 오버플로 | **독립 인터럽트 전용 스택** 할당 및 중첩 깊이 제한 | 커널 메모리 오염 방지 및 시스템 안정성 확보 |

#### 한줄 요약
- 실무에서는 Top-half/Bottom-half 분리로 ISR 지연을 최소화하고, 독립 인터럽트 스택으로 중첩 오버플로를 방지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **확장 메시지 시그널 인터럽트(Message Signaled Interrupts Extended, MSI-X)**: 전용 물리 핀 없이 PCIe 인밴드 패킷을 통해 최대 2,048개의 독립 벡터를 멀티코어 프로세서에 동적으로 분산 라우팅하는 인터럽트 규격.
- **인터럽트 요청 선호도(Interrupt Request Affinity, IRQ Affinity)**: 특정 장치의 인터럽트 처리를 지정된 CPU 코어에 고정 바인딩하여 코어 캐시 미스와 컨텍스트 스위칭 오버헤드를 억제하는 OS 커널 기술.

</details>

- 물리 핀 공유 기반의 전통적 인터럽트 제어는 가상화 및 고속 패브릭 환경에서 PCIe 인밴드 패킷 통신인 **확장 메시지 시그널 인터럽트(MSI-X)**와 결합하고, IOMMU 기반 가상 인터럽트 직접 주입(Posted Interrupts) 아키텍처로 진화 추세
- 고성능 네트워크 및 스토리지 인프라 운영 시에는 특정 코어로의 인터럽트 쏠림을 방지하기 위해 **인터럽트 요청 선호도(IRQ Affinity)** 바인딩을 적용하고, Top-half 최소화와 지연 처리를 결합하여 시스템 처리량과 응답 지연을 동시 최적화하는 공학적 통찰 필요

#### 한줄 요약
- 인터럽트 처리는 MSI-X와 가상화 직접 주입 체계로 진화하고 있으며, 실무에서는 IRQ 선호도 바인딩과 상·하반부 분리를 통한 코어 부하 분산이 핵심 통찰이다.
