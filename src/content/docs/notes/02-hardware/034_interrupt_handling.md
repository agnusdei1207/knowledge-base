## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: CPU가 명령을 실행하는 도중 주변 장치나 내부 예외가 발생했을 때, 현재 문맥을 보존하고 전용 ISR을 실행한 후 복귀하는 제어 메커니즘.
- **인터럽트 요청(IRQ)**: 주변 장치가 하드웨어 라인이나 메시지(MSI)를 통해 CPU에 즉각적인 처리를 요청하는 전기적 신호.
- **인터럽트 서비스 루틴(ISR)**: 해당 인터럽트를 전담하여 장치의 I/O 데이터를 인출하고 상태를 처리하는 커널 함수.

</details>

- 정의/개념: 주변장치의 비동기 이벤트 발생 시 **문맥 저장(Context Save)** 후 전용 처리 루틴(ISR)으로 분기하는 하드웨어 제어 기법
- 배경/필요성: 소프트웨어 폴링 방식의 **CPU 사이클 낭비** 및 다중 장치 동시 요청 시 우선순위 충돌 발생

#### 한줄 요약
- 외부 장치의 비동기 요청이 오면 하던 일을 멈추고 우선순위에 맞춰 전용 처리 루틴을 실행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **문맥 보존(Context Save)**: 현재 실행 중인 프로그램 카운터(PC)와 상태 레지스터(PSR)를 스택에 임시 저장하는 동작.
- **벡터 인터럽트(Vectored Interrupt)**: 장치가 제공하는 번호(Vector)로 시작 주소를 즉시 찾아 분기하는 방식.
- **데이지체인(Daisy Chain)**: 직렬 우선순위 승인 신호(INTA)를 연결해 가장 가까운 장치부터 선점하는 구조.

</details>

- **문맥 보존 및 복구**로 기존 실행 흐름에 투명한 비동기 복귀 지원
- **벡터 인터럽트**로 주소 직접 참조를 통한 초저지연 분기 지원
- **데이지체인 직렬 우선순위** 판별로 하드웨어 결선 단순화

#### 한줄 요약
- 현재 상태를 저장한 뒤 벡터나 데이지체인으로 우선순위를 가려 해당 처리 루틴으로 빠르게 이동한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 벡터 테이블(IVT)**: 인터럽트 번호별 ISR 시작 주소를 배열 형태로 저장하는 메모리 테이블.
- **APIC(Advanced Programmable Interrupt Controller)**: 다중 코어 환경에서 인터럽트를 분산 라우팅하는 고도화된 제어기.

</details>

```text
[ 주변장치 1 (최우선) ] ─── [ 주변장치 2 ] ─── [ 주변장치 N ]
         │ (INTA 승인선 직렬 통과)
         ▼
┌───────────────────────────────────────────────┐
│ 인터럽트 제어기 (PIC / APIC)                  │
│  ├─ 인터럽트 요청 레지스터 (IRR)              │
│  ├─ 우선순위 판별기 (Priority Resolver)       │
│  └─ 인터럽트 서비스 레지스터 (ISR Reg)        │
└───────────────────────┬───────────────────────┘
                        │ (INT 신호 / Vector 번호)
                        ▼
┌───────────────────────────────────────────────┐
│ CPU (문맥 스택 저장 → IVT 조회 → ISR 점프)   │
└───────────────────────────────────────────────┘
```

선의 의미: 상단은 장치 간 데이지체인 직렬 결선; 하단은 제어기와 CPU 간 인터럽트 전달 경로

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 제어기 | 다중 IRQ 수신, 우선순위 판정 및 CPU에 INT 신호 전달 |
| 인터럽트 벡터 테이블 | 인터럽트 번호에 대응하는 ISR 시작 메모리 주소 매핑 |
| 인터럽트 서비스 루틴 | 장치 상태 읽기, 에러 플래그 리셋 및 I/O 데이터 처리 |
| 문맥 스택 메모리 | 인터럽트 진입 전 PC, 범용 레지스터, 플래그 안전 보존 |

#### 한줄 요약
- 제어기가 우선순위를 판정해 CPU에 알리면, CPU는 문맥을 저장하고 IVT를 통해 ISR을 실행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IRET(Interrupt Return)**: 스택에 저장된 PC와 플래그를 복원하여 인터럽트 발생 전 명령어로 복귀하는 명령어.

</details>

```text
주변장치: 인터럽트 요청 (IRQ)
      │
      ▼
1. 인터럽트 요청 수신 및 우선순위 판정
      │
      ▼
2. 현재 실행 문맥 스택 저장 (PC, PSR)
      │
      ▼
3. 인터럽트 벡터 테이블 조회 및 ISR 점프
      │
      ▼
4. ISR 실행 및 장치 I/O 처리
      │
      ▼
5. 문맥 복원 및 원래 명령 복귀 (IRET)
```

**동작 원리**

1. **요청 수신 및 우선순위 판정**: 제어기가 여러 IRQ 중 최우선 장치를 선별해 CPU에 전달
2. **현재 실행 문맥 저장**: CPU가 현재 명령어 완료 후 PC와 상태 레지스터를 스택에 대피
3. **벡터 조회 및 ISR 점프**: 인터럽트 번호로 IVT를 조회해 해당 ISR 시작 주소로 분기
4. **ISR 실행 및 장치 I/O 처리**: 실제 장치 데이터를 읽고 상태 레지스터 플래그 초기화
5. **문맥 복원 및 복귀**: IRET 명령어로 스택 문맥을 복구해 중단되었던 프로그램 재개

#### 한줄 요약
- 요청 수신 → 우선순위 판정 → 문맥 저장 → ISR 실행 → 문맥 복원 후 복귀 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 인터럽트 판별 방식 | 벡터 인터럽트 (Vectored) | 비벡터 인터럽트 (Non-Vectored) | 데이지체인 (Daisy Chain) | 소프트웨어 폴링 (Polling) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 고속 응답·대규모 다중 코어 시스템 | 단순 단일 인터럽트 임베디드 | 결선 최소화 필요 하드웨어 버스 | 초소형 저비용 마이크로컨트롤러 |
| 핵심 특징 | 장치가 직접 벡터 번호 전달·즉시 분기 | 고정 번지로 점프 후 소프트웨어 판별 | 직렬 승인 신호로 하드웨어 우선순위 결정 | 공통 인터럽트 후 루프 조회로 소스 확인 |
| 한계 | 버스 신호선 및 전용 하드웨어 비용 | 다중 인터럽트 시 지연시간 증가 | 뒤쪽 장치의 기아(Starvation) 위험 | 장치 수 증가 시 폴링 지연 선형 증가 |

#### 한줄 요약
- 빠른 분기는 벡터, 단순 구조는 비벡터, 배선 절약은 데이지체인, 소형 시스템은 폴링을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Top-half / Bottom-half**: 긴급한 하드웨어 처리는 상반부(Top-half)에서 즉시 끝내고, 무거운 후속 작업은 하반부(Bottom-half)로 지연 처리하는 기법.
- **인터럽트 네스팅(Interrupt Nesting)**: ISR 실행 중 더 높은 우선순위의 인터럽트가 오면 현재 ISR을 중단하고 새 ISR을 우선 실행하는 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISR 내부 처리 지연으로 다른 인터럽트 차단 | **Top-half / Bottom-half** 분리 구조 적용 | 인터럽트 응답성 확보 및 지연 최소화 |
| 고우선순위 장치 집중으로 저우선순위 기아 | 회전 우선순위(Rotating Priority) 스케줄링 | 모든 장치에 공평한 처리 기회 보장 |
| 동일 IRQ 선로를 복수 장치가 공유 시 충돌 | 공통 ISR 체이닝 및 상태 레지스터 신속 검사 | 공유 인터럽트 오동작 방지 |
| 빈번한 중첩 인터럽트로 인한 **스택 오버플로** | 네스팅 깊이 제한 및 전용 인터럽트 스택 할당 | 시스템 충돌 방지 및 커널 안정성 확보 |

#### 한줄 요약
- 상하반부 분리로 ISR을 가볍게 만들고, 회전 우선순위와 전용 스택으로 기아와 오버플로를 방지한다.

## Ⅶ. 결론

- 초저지연 고속 시스템은 **벡터 인터럽트**, 단순 배선 구조는 **데이지체인** 선택

#### 한줄 요약
- 응답 속도와 하드웨어 비용, 장치 개수를 종합 분석해 최적의 인터럽트 판별 방식을 구성해야 한다.
