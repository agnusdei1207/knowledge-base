## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: 중앙처리장치가 연산을 수행하던 도중 외부 장치나 내부 예외 신호가 수신되면, 현재 구동 중인 상태 문맥을 안전하게 백업하고 전용 처리 루틴으로 제어를 전환하여 사태를 수습한 후 본래 흐름으로 복귀하는 전체 제어 시퀀스이다.
- **인터럽트 요청 신호(Interrupt Request)**: 주변기기, 타이머, 디스크 제어기 등이 하드웨어 핀이나 메시지를 통해 중앙처리장치에 즉각적인 처리를 요구함을 긴급 전달하는 전기적 혹은 논리적 신호이다.
- **인터럽트 서비스 루틴(Interrupt Service Routine)**: 특정 요청 번호에 일대일로 결합되어, 실제로 장치의 입출력 데이터를 인출하거나 상태 레지스터를 초기화해 주는 운영체제 커널 내부의 전용 함수이다.

</details>

- 정의: 비동기적 하드웨어 및 소프트웨어 요청을 수신하여 전용 제어기가 우선순위를 중재하고, 중앙처리장치가 문맥 저장 후 해당 **인터럽트 서비스 루틴**을 실행하여 원래 상태로 복귀시키는 **인터럽트 처리** 아키텍처
- 배경: 프로세서가 주변장치의 완료 여부를 주기적으로 확인하며 낭비하는 바쁜 대기의 막대한 연산 자원 낭비를 완전히 소거하고 입출력 완료 및 비상 트랩에 즉각 반응하기 위함

#### 한줄 요약

- 하드웨어 긴급 신호 수신 시, 프로세서의 현재 문맥을 저장하고 식별자를 기반으로 전용 서비스 루틴을 점프 실행한 뒤 본래 작업으로 매끄럽게 복원하는 통제 메커니즘이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인터럽트 지연(Interrupt Latency)**: 하드웨어 요청 신호가 전기적으로 발생한 순간부터, 중앙처리장치가 모든 문맥 저장을 마치고 실제 서비스 루틴의 첫 번째 기계어 명령어를 실행하기 직전까지 소요되는 민감한 대기 시간이다.
- **중첩 인터럽트(Nested Interrupt)**: 어떤 서비스 루틴이 구동 중일 때, 그보다 더 우선순위가 높은 치명적 요청이 들어오면 기존 루틴의 실행을 중단하고 새로운 루틴을 우선 실행하는 유연한 구조이다.
- **문맥 저장 및 복원(Context Save and Restore)**: 중앙처리장치의 프로그램 카운터, 스택 포인터, 범용 레지스터 및 상태 레지스터의 현재 찰나를 커널 메모리 스택에 넣고 빼는 고비용 작업이다.

</details>

- 허용된 경계에서 인터럽트를 즉각 수락하고, 하드웨어적 우선순위 및 마스크 검사 후 신속한 실행 흐름 전환을 발동함.
- 전용 하드웨어 제어기를 탑재하여 다중 장치에서 쏟아지는 동시다발적 인터럽트 간의 마스킹 및 물리적 우선순위 중재를 엄격히 통제함.
- 긴급도가 높은 요청 수용을 위해 **중첩 인터럽트**를 허용하되, 이로 인한 예기치 않은 **인터럽트 지연**의 상승 및 커널 스택 오버플로 위험을 구조적으로 수반함.

#### 한줄 요약

- 제어기의 우선순위 중재와 코어의 문맥 저장 및 복원, 그리고 중첩 제어를 유기적으로 결합하여 동시다발적인 하드웨어 요청을 순서대로 빈틈없이 수습한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 제어기(Interrupt Controller)**: 각 주변장치의 수많은 요청 핀을 1차적으로 집적 받아 마스킹 및 우선순위 판정을 마친 뒤, 중앙처리장치 코어로 대표 신호를 발송하는 전용 중재 반도체 칩이다.
- **인터럽트 벡터 테이블(Interrupt Vector Table)**: 메모리의 고정된 번지 구역에 배치되어, 각 인터럽트 벡터 번호마다 처리해야 할 32비트 혹은 64비트 서비스 루틴의 시작 메모리 주소를 매핑해둔 거대한 함수 포인터 배열이다.
- **인터럽트 벡터(Interrupt Vector)**: 해당 요청을 발생시킨 장치가 8비트 데이터 버스를 통해 중앙처리장치에 직접 전송해 주는 장치의 고유 신원 오프셋 번호이다.

</details>

```text
[ 하드웨어 인터럽트 제어기 및 벡터 테이블 아키텍처 ]
+-------------------------------------------------------------+
| 주변 입출력 장치 (타이머, 고속 스토리지, 네트워크 카드)     |
|  └─ 개별 하드웨어 요청 신호 발생 (요청 0 ~ 요청 N)          |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 전용 하드웨어 인터럽트 제어기                               |
|  ├─ 다중 요청 핀 마스킹 및 우선순위 중재 판정 로직          |
|  └─ 승리한 장치의 고유 벡터 번호를 코어로 최종 송출         |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 중앙처리장치 코어                                           |
|  ├─ 제어기로부터 고유 인터럽트 벡터 번호 수신               |
|  ├─ 내부 레지스터 상태를 커널 메모리 스택에 안전하게 보존   |
|  └─ 벡터 테이블에서 번호를 색인하여 타깃 루틴 주소로 점프   |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **인터럽트 제어기** | 무수히 쏟아지는 개별 요청의 마스킹, 우선순위 판정 및 물리적 코어 라우팅 제어 총괄 |
| **인터럽트 벡터** | 중앙처리장치가 즉각 처리해야 할 대상 장치의 고유 색인 식별 번호 직접 제공 |
| **인터럽트 벡터 테이블** | 고유 벡터 번호별로 지정된 운영체제 커널 서비스 루틴의 시작 메모리 물리 주소 영구 보관 |
| 인터럽트 종료 신호 | 제어기에 현재 서비스 루틴 처리 완료 및 다음 대기 중인 인터럽트 수신 허용 명시적 통지 |

#### 한줄 요약

- 장치가 요청을 보내면 제어기가 중재하여 번호를 넘기고, 프로세서는 그 번호로 테이블을 조회하여 지정된 주소의 함수를 신속하게 실행하는 연계 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **원인 해제(Source Clear)**: 서비스 루틴 함수 내부에서 입출력 장치 컨트롤러의 상태 레지스터 비트를 직접 0으로 덮어써서 동일한 전기적 신호가 불필요하게 재발동되는 것을 막는 치명적 방어 행위이다.
- **지연 처리(Deferred Processing)**: 서비스 루틴 전반부에서는 장치 상태 확인과 원인 해제만 1마이크로초 내로 번개처럼 처리하고, 패킷 조립 등 시간이 걸리는 복잡한 처리는 하반부 큐로 미루어 넘기는 운영체제 설계 기법이다.

</details>

```text
[ 하드웨어 디바이스의 인터럽트 요청 신호 물리적 발생 ]
                      │
                      ▼
   [ 1. 제어기의 다중 신호 물리적 중재 및 식별 ]
                      │
                      ▼
  [ 2. 프로세서의 현재 문맥 커널 스택 안전 보존 ]
                      │
                      ▼
    [ 3. 대상 인터럽트 서비스 루틴 함수 점프 실행 ]
                      │
          [ 복잡한 지연 처리 작업 존재 여부 ]
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
[ 아니오 정상 처리 ] [ 예 (하반부 작업 큐 지연 등록) ]
        │                           │
        └─────────────┬─────────────┘
                      ▼
    [ 4. 인터럽트 종료 신호 발송 및 문맥 완벽 복원 ]
```

### 동작 원리

1. 중재 및 식별: 제어기가 인터럽트 마스크 및 우선순위를 엄격히 검사하고 승리한 장치의 벡터를 중앙처리장치로 송출함.
2. 문맥 저장: 프로세서가 현재의 프로그램 카운터와 핵심 상태 레지스터를 스택 메모리에 안전하게 보존함.
3. 서비스 루틴 실행: 지정된 루틴으로 즉시 점프하여 하드웨어 **원인 해제**를 수행하고 무거운 작업을 지연 큐에 등록함.
4. 지연 처리 및 복원: **지연 처리**를 백그라운드로 예약하고 백업된 문맥을 스택에서 복원하여 멈췄던 원래 흐름으로 복귀함.

#### 한줄 요약

- 우선순위를 판단하고 하던 일을 저장한 뒤, 원인을 제거하고 무거운 작업은 미루면서 잽싸게 원래 자리로 돌아오는 신속 대응 파이프라인이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **벡터 방식(Vectored Interrupt)**: 장치가 자신의 고유 벡터 번호를 데이터 버스를 통해 직접 응답하여, 중앙처리장치가 식별 지연 없이 테이블을 즉시 조회해 단번에 점프하는 현대적 고성능 하드웨어 방식이다.
- **데이지체인 방식(Daisy Chain Interrupt)**: 여러 장치가 단일 인터럽트 선과 승인 선을 꼬리물기 직렬 체인으로 연결하여, 물리적 거리가 가까운 순서대로 권한을 가로채어 원인을 탐색하는 비용 절감형 임베디드 방식이다.

</details>

| 비교 항목 | **벡터 방식** | **데이지체인 방식** |
|:---|:---|:---|
| 원인 장치 식별 메커니즘 | 요청 장치가 자신만의 고유 **인터럽트 벡터** 번호를 데이터 버스로 코어에 직접 송출 | 제어기의 승인 신호를 물리적으로 연결된 직렬 체인 핀 라인으로 순차적으로 패스 전달 |
| 우선순위 중재 결정 방식 | 전용 하드웨어 제어기의 프로그래밍된 내부 레지스터 설정값에 따라 논리적 획득 | 물리적 하드웨어 와이어 연결 순서에 따라 프로세서에 가장 가까운 장치가 무조건 선점 |
| 식별 대기 지연시간 소모 | 테이블 주소 직접 룩업 점프로 극도로 짧고 모든 장치에 대해 일정하게 보장됨 | 체인을 따라 전기적 신호가 전파되고 탐색되어야 하므로 하위 장치일수록 긴 편임 |
| 하드웨어 설계 구현 복잡도 | 별도의 값비싼 전용 제어기 반도체 칩 및 다가닥의 병렬 데이터 버스 라인이 필수적임 | 단일 인터럽트 요청 핀과 단일 승인 핀 라인만으로 다수 장치를 묶을 수 있어 매우 단순함 |
| 대표적 채택 적용 아키텍처 | 개인용 컴퓨터, 엔터프라이즈 서버, 고성능 모바일 애플리케이션 프로세서 및 최신 아키텍처 | 핀 수가 부족하고 비용 제약이 극심한 소형 임베디드 기기 및 8비트 마이크로컨트롤러 유닛 |

#### 한줄 요약

- 벡터 방식은 돈이 들지만 번호표를 뽑아 빠르고 정확하게 점프하는 현대적 표준이며, 데이지체인은 핀 하나로 엮어 앞에서부터 검사하는 극강의 가성비 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상반부 및 하반부 분리(Top-Half and Bottom-Half Separation)**: 루틴 전반부(상반부)에서는 하드웨어 통제 권한만 가볍게 해결하고, 무거운 데이터 처리 로직은 백그라운드 소프트웨어 인터럽트(하반부)로 미루어 코어 독점을 억제하는 고도화된 커널 분리 기법이다.
- **우선순위 노화(Priority Aging)**: 제어기 스케줄링 시 우선순위가 낮은 장치가 높은 장치에 밀려 영원히 무시당하는 기아 현상을 막고자, 대기 시간에 비례해 일시적으로 인터럽트 우선순위를 끌어올려 주는 기법이다.
- **인터럽트 친화도(Interrupt Affinity)**: 다중 코어 시스템에서 특정 고속 장치의 인터럽트 신호를 특정 코어에만 일대일로 꽂히도록 강제 바인딩하여, 코어 간 무의미한 핑퐁과 캐시 미스를 차단하는 커널 최적화 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서비스 루틴 코드가 무겁고 길어져 시스템 전체의 다른 인터럽트가 영구적으로 무한 대기 지연되는 현상 발생 | **상반부 및 하반부 분리**를 통한 무거운 작업의 백그라운드 지연 큐 적극적 위임 아키텍처 도입 | 서비스 루틴의 실제 코어 점유 실행 시간을 마이크로초 단위로 극소화 및 시스템 전반의 반응성 100% 확보 |
| 고장 난 불량 하드웨어 디바이스에서 의미 없는 요청 신호가 초당 수십만 번씩 끊임없이 터져 나오는 폭주 현상 | 운영체제 커널 차원의 다중 인터럽트 병합 기술 튜닝 및 임계치 초과 시 장애 장치 영구 비활성화 | 프로세서 코어 마비 현상 및 자원 고갈 원천 차단 및 무중단 서버 시스템 구동 안정성 확보 보장 |
| 멀티코어 환경에서 방대한 입출력 요청 신호가 단일 0번 코어로만 가혹하게 집중되어 병목과 부하 불균형 초래 | **인터럽트 친화도** 마스크 강제 바인딩 튜닝 및 동적 부하 분산 스케줄링 데몬 백그라운드 구동 | 다중 코어 간의 입출력 인터럽트 처리 부하를 완벽히 균등 분산시키고 전체 시스템 처리 대역폭 극대화 |
| 잦은 중첩 인터럽트로 인해 스택 호출 깊이가 걷잡을 수 없이 깊어져 한정된 커널 스택 메모리가 붕괴됨 | 커널 및 펌웨어 레벨의 중첩 호출 깊이 강제 제한 설정 및 인터럽트 처리를 위한 전용 독립 스택 공간 분리 할당 | 커널 스택 메모리 꼬리 파손 및 그로 인한 치명적인 시스템 전체 크래시 현상 물리적 사전 예방 |

#### 한줄 요약

- 상하반부 분리로 반응 속도를 지켜내고, 인터럽트 친화도로 코어 쏠림을 막으며, 전용 스택과 횟수 제한으로 중첩 깊이로 인한 커널 파손을 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **인터럽트 아키텍처 결정 기준(Interrupt Architecture Decision Criteria)**: 대상 하드웨어 시스템의 인터럽트 발생 빈도, 절대 허용 지연시간 한계, 장착된 중앙처리장치 코어 개수 및 물리적 하드웨어 핀 제약을 종합적으로 수치 평가하여 최적의 식별 방식과 지연 처리 구조를 확정하는 결정 프레임워크이다.

</details>

- 다중 코어 및 고성능 요구 시스템은 **벡터 방식과 메시지 시그널 인터럽트**, 핀 개수 및 물리적 제약이 극심한 보드는 **데이지체인 방식**을 선택함

#### 한줄 요약

- 빈도와 요구 지연시간, 그리고 물리적 핀 제약을 정밀하게 저울질하여 값비싼 병렬 벡터 방식을 쓸지 저렴한 직렬 연결을 쓸지, 지연 처리를 얼마나 쪼갤지 확정해야 한다.
