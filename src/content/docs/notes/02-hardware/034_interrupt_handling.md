## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터럽트 처리(Interrupt Handling)**: CPU가 명령어를 순차 실행하는 도중 외부 I/O 장치의 비동기 요청이나 내부 예외가 발생했을 때, 현재 실행 문맥을 스택에 보존하고 해당 ISR(인터럽트 서비스 루틴)로 분기하여 처리한 후 복귀하는 하드웨어-소프트웨어 제어 메커니즘.
- **인터럽트 요청(Interrupt Request, IRQ)**: 주변 장치가 하드웨어 신호선 또는 PCIe MSI 메시지를 통해 CPU에 즉각적인 서비스 처리를 요청하는 전기적 신호.
- **인터럽트 서비스 루틴(Interrupt Service Routine, ISR)**: 특정 인터럽트 발생 시 해당 장치의 데이터를 처리하고 상태 플래그를 클리어하는 커널 핸들러 함수.

</details>

- 정의/개념: 비동기 인터럽트 발생 시 소스를 판별하고 우선순위에 따라 문맥을 교환하여 ISR을 실행하는 **인터럽트 처리** 아키텍처
- 배경/필요성: 폴링은 대기 중 **CPU 자원 낭비**, 동시 요청의 우선 처리 곤란

#### 한줄 요약
- 인터럽트 처리는 비동기 이벤트 발생 시 CPU가 문맥을 저장하고 전용 ISR을 실행한 뒤 원래 작업으로 복귀하는 하드웨어 제어 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **문맥 보존(Context Save)**: 현재 실행 중인 프로그램 카운터(PC)와 상태 레지스터(PSR/EFLAGS) 및 범용 레지스터를 프로세스 스택에 안전하게 백업하는 동작.
- **벡터 인터럽트(Vectored Interrupt)**: 인터럽트를 발생시킨 장치가 고유 벡터 번호를 데이터 버스로 공급하여 CPU가 ISR 시작 주소를 직접 조회(Direct Indexing)하는 고속 방식.
- **데이지체인(Daisy Chain)**: 직렬 우선순위 승인선(INTA)을 물리적으로 연결하여 CPU와 가장 가까운 상위 장치가 인터럽트 제어권을 선점하는 하드웨어 구조.

</details>

- 하드웨어 문맥 보존: 인터럽트 진입 시 하드웨어가 자동으로 **프로그램 카운터**와 상태 레지스터를 스택에 저장하여 무손실 복귀 보장
- 소스 판별 고속화: **벡터 인터럽트**를 통해 소프트웨어 탐색 없이 1사이클 내에 ISR 시작 주소로 분기
- 하드웨어 우선순위 중재: **데이지체인** 또는 프로그래머블 인터럽트 제어기를 통해 다중 IRQ 충돌 시 긴급 장치 우선 처리

#### 한줄 요약
- 벡터 번호로 ISR 분기 시간을 단축하고, 데이지체인이나 APIC로 우선순위를 중재하며, 스택 기반 문맥 보존으로 실행 흐름을 복구한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인터럽트 벡터 테이블(Interrupt Vector Table, IVT / IDT)**: 인터럽트 벡터 번호를 인덱스로 하여 각 ISR의 시작 주소 포인터를 배열 형태로 저장하는 메모리 테이블.
- **인터럽트 제어기(APIC / PIC)**: 다수의 외부 IRQ 신호를 수신하여 마스킹(Masking), 우선순위 판정 및 CPU 코어로의 라우팅을 총괄하는 하드웨어 제어기.

</details>

```text
[인터럽트 처리 구조]
 ├── [인터럽트 제어기]
 │    ├── 요청 레지스터
 │    ├── 우선순위 판별기
 │    └── 서비스 레지스터
 ├── [CPU 코어]
 ├── [인터럽트 벡터 테이블]
 ├── [인터럽트 서비스 루틴]
 └── [문맥 보존 스택]
```

선의 의미: 가지(`├──`, `└──`)는 인터럽트 처리 체계의 포함 관계

| 구성요소 | 책임 |
|:---|:---|
| 인터럽트 제어기 (APIC) | IRQ 우선순위 판정과 **MSI-X** 기반 코어 분산 |
| 인터럽트 벡터 테이블 (IVT) | 벡터와 ISR 주소 매핑, **IDTR 레지스터** 참조 |
| 인터럽트 서비스 루틴 (ISR) | 장치 처리와 **Top/Bottom-half** 분리 |
| 문맥 보존 스택 | 레지스터 백업과 **IRET 명령어** 복원 |

#### 한줄 요약
- 인터럽트 시스템은 APIC 제어기, 인터럽트 벡터 테이블(IVT), 드라이버 ISR, 문맥 보존 스택으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IRET(Interrupt Return)**: 스택에 보존되었던 PC와 플래그 레지스터를 복원하여 인터럽트 발생 전 명령어로 실행 흐름을 원자적으로 되돌리는 명령어.

</details>

```text
주변장치에서 인터럽트 요청(IRQ) 발생
                      │
                      ▼
인터럽트 제어기(APIC): 마스크 확인 및 우선순위 판정
                      │
                      ▼
CPU 코어: 현재 기계어 명령어 완료 후 인터럽트 수락 (INTA)
                      │
                      ▼
하드웨어 문맥 보존: PC와 PSR을 스택에 Push
                      │
                      ▼
벡터 번호 인출 및 인터럽트 벡터 테이블(IVT) 조회
                      │
                      ▼
ISR 실행 (장치 I/O 처리 및 인터럽트 플래그 클리어)
                      │
                      ▼
IRET 명령어 실행: 이전 PC 및 PSR 복원 후 프로그램 재개
```

분기 결과: 우선순위 높은 인터럽트 우선 처리, ISR 완료 후 **IRET**로 원래 작업 복구

#### 한줄 요약
- IRQ 발생 ➔ APIC 판정 ➔ CPU 수락 ➔ 문맥 스택 저장 ➔ IVT 조회 및 ISR 실행 ➔ IRET 문맥 복원의 순서로 동작한다.

## Ⅴ. 종류 및 비교

| 인터럽트 판별 방식 | 벡터 인터럽트 (Vectored) | 비벡터 인터럽트 (Non-Vectored) | 데이지체인 (Daisy Chain) | 소프트웨어 폴링 (Polling) |
|:---|:---|:---|:---|:---|
| 판별 주체 | 하드웨어 (**벡터 번호** 송출) | 소프트웨어 (고정 시작점 탐색) | 하드웨어 (**직렬 INTA** 전파) | 소프트웨어 (상태 레지스터 검사) |
| 소스 식별 지연 | **초고속** (IVT 직접 조회) | 느림 (순차 상태 검사) | 빠름 (신호 전파 지연) | 매우 느림 (장치 수 비례) |
| 우선순위 결정 방식 | **APIC 레지스터** 설정 | 소프트웨어 조건문 순서 | **물리적 배선** 순서 | 소프트웨어 루프 순서 |
| 하드웨어 비용 | 중간 (인터럽트 제어기) | 매우 낮음 | 낮음 (직렬 승인선) | 없음 (추가 회로 없음) |
| 주요 적용 분야 | 현대 멀티코어 (**x86/ARM**) | 단순 레거시 MCU | 산업용 VME 버스 | 초단순 센서 제어 |

#### 한줄 요약
- 현대 고성능 시스템은 APIC 기반 벡터 인터럽트가 표준이며, 단순 배선에는 데이지체인이, 초단순 시스템에는 소프트웨어 폴링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Top-half / Bottom-half**: 긴급한 하드웨어 ACK 처리는 상반부(Top-half)에서 즉시 끝내고, 무거운 데이터 처리는 하반부(Bottom-half / SoftIRQ)로 지연 처리하는 기법.
- **인터럽트 네스팅(Interrupt Nesting)**: ISR 실행 중 더 높은 우선순위 인터럽트의 중첩 진입을 허용하는 구조.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISR 처리 지연으로 타 인터럽트 차단 | **Top-half/Bottom-half** 분리 처리 | 응답 지연시간 단축 |
| 특정 장치의 인터럽트 독점 및 기아 | **회전 우선순위** 및 인터럽트 완화 | 공정한 처리 기회 보장 |
| 인터럽트 중첩으로 커널 스택 넘침 | **독립 인터럽트 스택** 할당 및 깊이 제한 | 스택 오버플로 방지 |

#### 한줄 요약
- 실무에서는 Top-half/Bottom-half 분리로 ISR 지연을 최소화하고, 독립 인터럽트 스택으로 중첩 오버플로를 방지한다.

## Ⅶ. 결론

- 다중 장치·저지연은 **벡터 인터럽트**, 단순 고정 우선순위는 **데이지체인** 선택

#### 한줄 요약
- 인터럽트 처리는 APIC 벡터 구조와 Top-half/Bottom-half 분리를 통해 초저지연과 시스템 안정성을 동시에 달성한다.
