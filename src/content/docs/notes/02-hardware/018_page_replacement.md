## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지 교체(Page Replacement)**: 물리 메모리가 포화 상태일 때 신규 페이지 적재 공간을 확보하기 위해 기존 상주 페이지 중 희생 페이지를 선택하여 방출하는 알고리즘.
- **희생 페이지(Victim Page)**: 새로 요청된 페이지를 위해 물리 프레임에서 축출되는 대상 페이지.
- **페이지 폴트(Page Fault)**: 접근하려는 가상 페이지가 물리 메모리에 없어 디스크에서 적재해야 하는 OS 예외 트랩.

</details>

- 정의/개념: 물리 메모리가 포화되어 새로운 페이지를 적재할 공간이 없을 때, 미래 참조 가능성이 가장 낮은 희생 페이지(Victim Page)를 선택 축출하는 메모리 관리 알고리즘
- 배경/필요성: 비효율적 페이지 축출로 인한 **빈번한 페이지 폴트(Page Fault) 및 스왑 I/O 병목(Thrashing) 방지**

#### 한줄 요약

- 물리 프레임 포화 시 미래 재참조 확률이 가장 적은 **희생 페이지를 선택 축출**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **참조 지역성(Reference Locality)**: 최근 참조된 페이지가 곧 다시 참조되는 시간 지역성과 인접 주소가 참조되는 공간 지역성.
- **벨라디의 모순(Bélády's Anomaly)**: FIFO 알고리즘 등에서 물리 프레임 수를 늘려주었음에도 오히려 페이지 폴트 횟수가 증가하는 역설적 현상.

</details>

- **참조 지역성(시간/공간)**을 기반으로 미래 재참조 가능성이 가장 낮은 희생 페이지 선정
- 알고리즘 정밀도와 매 참조 시 하드웨어 상태 갱신(타임스탬프, 참조 비트) 오버헤드 간 트레이드오프
- 축출 대상이 **더티 페이지(Dirty Page)**일 경우 디스크 스왑 영역 쓰기 I/O 오버헤드 수반

#### 한줄 요약

- **시간·공간 지역성**을 반영하며, 알고리즘 정밀도와 갱신 오버헤드 간 트레이드오프

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상주 프레임 집합**: 물리 DRAM에 매핑되어 유효하게 구동 중인 페이지 목록.
- **후면 저장소(Backing Store / Swap Space)**: 물리 메모리에서 축출된 페이지 데이터를 임시 보관하는 디스크/SSD 스왑 영역.

</details>

```text
[ 물리 메모리 프레임 집합 및 참조 이력 관리 ]
                   │
                   ▼
      [ 페이지 교체 알고리즘 엔진 구동 ]
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
 [ Clean 희생 페이지 ]   [ Dirty 희생 페이지 (수정됨) ]
        │                     │
        ▼                     ▼
 [ 즉시 프레임 회수 ]    [ 스왑 저장소 쓰기 (Swap-Out) ]
        │                     │
        └──────────┬──────────┘
                   ▼
       [ 신규 요청 페이지 적재 (Swap-In) ]
```

선의 의미: 상주 프레임 집합과 참조 이력 추적기, 교체 선택기 및 스왑 I/O 장치 간의 페이지 교체 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 상주 프레임 집합 | 물리 프레임에 적재된 페이지 목록과 유효 상태 관리 |
| 참조 이력 매핑 | 페이지 교체를 위한 시각 및 횟수, 참조 비트 추적 기록 |
| 교체 선택기 | 적용된 알고리즘 정책에 따라 축출할 희생 프레임 결정 |
| 저장소 입출력 | 변경된 희생 페이지 저장 및 신규 요청 페이지 적재 수행 |

#### 한줄 요약

- **상주 프레임 목록·참조 이력 비트·교체 엔진·스왑 저장소**의 유기적 연동

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스왑 아웃(Swap-Out) / 스왑 인(Swap-In)**: 메모리 희생 페이지를 디스크로 내보내는 Swap-Out과 디스크 페이지를 메모리로 올리는 Swap-In.

</details>

```text
[ 비상주 페이지 폴트 발생 ]
            │
            ▼
     [ 빈 물리 프레임 점검 ]
            │
      ┌─────┴─────┐
      ▼           ▼
[ 빈 프레임 없음 ] [ 빈 공간 존재 ]
      │           │
      ▼           │
[ 교체 알고리즘으로 희생 페이지 선정 ] │
      │           │
      ▼           │
[ Dirty 시 Swap-Out / Clean 시 파기 ] │
      │           │
      └─────┬─────┘
            ▼
    [ 디스크에서 신규 페이지 Swap-In ]
            │
            ▼
    [ PTE 갱신 및 명령어 재시작 ]
```

**동작 원리**

1. **프레임 점검**: 빈 물리 프레임이 없을 경우 페이지 교체 엔진 구동
2. **희생 페이지 선정**: 알고리즘(LRU, Clock 등)에 따라 참조 이력을 대조하여 희생 페이지 특정
3. **스왑 아웃**: 희생 페이지의 Dirty 비트가 1이면 디스크 스왑 영역에 기록 후 프레임 해제
4. **적재 및 복구**: 신규 페이지를 빈 프레임에 Swap-In 적재하고 페이지 테이블(PTE) 갱신 후 명령어 재시작

#### 한줄 요약

- 빈 프레임 확인 후 **희생 페이지 선정, 더티 스왑 아웃, 신규 페이지 스왑 인** 완료

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OPT / FIFO / LRU / Clock**:
  - OPT (Optimal): 미래 최장 미사용 페이지 축출 (이론적 상한선)
  - FIFO: 가장 먼저 들어온 페이지 축출 (벨라디의 모순 발생)
  - LRU: 가장 오랫동안 참조되지 않은 페이지 축출 (최적 근사)
  - Clock (Second Chance): 1-bit 참조 비트와 원형 큐 포인터 기반 LRU 하드웨어 근사

</details>

| 교체 알고리즘 | 최적 교체 (OPT) | 선입선출 (FIFO) | 최근 최소 사용 (LRU) | 클록 알고리즘 (Clock/NUR) |
|:---|:---|:---|:---|:---|
| 희생 판단 기준 | 향후 가장 오랫동안 사용되지 않을 페이지 | 메모리에 가장 먼저 적재된 페이지 | 가장 오랫동안 참조되지 않은 페이지 | 1-bit 참조 비트 기반 순환 포인터 검사 |
| 핵심 특징 | 이론상 최저 폴트율 (비교 기준점/오프라인) | 큐(Queue)로 구현 단순, 벨라디의 이상 발생 | 시간 지역성 반영, 타임스탬프/더블 링크드 리스트 | LRU의 실용적 근사(Approximate), 하드웨어 오버헤드 최소 |
| 한계 및 위험 | 미래 참조열을 미리 알 수 없어 구현 불가 | 오래 머문 자주 쓰이는 페이지 축출 위험 | 매 참조 시 타임스탬프/리스트 갱신 오버헤드 | 루프 순환 시 참조 비트 전수 0 리셋 오버헤드 |

#### 한줄 요약

- 이론상 최적(OPT) 대비 실무에서는 **LRU의 하드웨어 근사치인 클록 알고리즘(Second Chance)** 표준 활용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **kswapd (Linux Page Stealing Daemon)**: 가용 메모리가 워터마크 이하로 떨어지면 백그라운드에서 미리 비활성 페이지를 스왑 아웃시키는 비동기 데몬.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 사용 갱신 비용에 따른 막대한 하드웨어 전력 소모 및 병목 | 1비트 참조 비트 기반 **클록 알고리즘** 하드웨어 적용 | 관리 오버헤드 극소화 및 유사 교체 성능 보장 |
| 선입선출 적용 시 메모리를 늘려도 폴트가 늘어나는 **벨라디의 이상** | 최소 최근 사용 및 스택 속성의 **클록 알고리즘** 적용 | 비정상적인 폴트 급증 이상 현상 원천 차단 |
| 빈도 사용 시 과거에 참조된 초기 데이터가 퇴출되지 않는 현상 | 일정 시간 주기로 동작하는 **카운터 감쇠** 연동 | 최신 지역성 반영 및 오래된 데이터 메모리 오염 방지 |
| 변경 페이지 축출 시 디스크 입출력으로 인한 명령어 처리 정지 | 운영체제 커널 차원의 비동기 **백그라운드 기록** 가동 | 페이지 교체 시 동기적 입출력 대기 시간 완벽 은닉 |

#### 한줄 요약

- **클록 알고리즘·카운터 감쇠(LFU)·비동기 플러시(kswapd)**로 교체 성능 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **2Q / W-TinyLFU**: 최근 참조(Recency)와 참조 빈도(Frequency)를 결합하여 스캔 저항성(Scan Resistance)을 갖춘 현대 캐시/페이지 교체 알고리즘.

</details>

- 리눅스 등 범용 커널은 **활성/비활성 2중 리스트 기반 클록/LRU 알고리즘(kswapd) 표준 채택**

#### 한줄 요약

- **하드웨어 갱신 오버헤드 최소화와 지역성 보존**을 절충한 클록/LRU 엔진 적용
