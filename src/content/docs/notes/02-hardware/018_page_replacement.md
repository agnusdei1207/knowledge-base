## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **페이지 교체**: 빈 물리 프레임이 없을 때 희생 페이지를 선택해 요청 페이지의 공간을 확보하는 정책이다.
- **희생 페이지**: 새 페이지를 적재할 프레임을 만들기 위해 퇴출하는 기존 페이지이다.
- **페이지 폴트**: 비상주 페이지 접근을 운영체제에 알리는 예외이다.
- **입출력(Input/Output, I/O)**: 저장장치에서 페이지를 읽거나 쓰는 처리이다.

</details>

- 정의/개념: 빈 물리 프레임이 없을 때 퇴출할 페이지를 결정하는 **희생 페이지 선택 정책**이다.
- 배경/필요성: 재사용할 페이지를 잘못 퇴출하면 다시 적재해야 하므로 페이지 폴트와 저장장치 I/O가 증가한다.

#### 한줄 요약

- 페이지 교체는 재사용 가능성이 낮은 페이지를 퇴출하고, 수정된 페이지는 저장장치에 기록한 뒤 요청 페이지를 적재한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **참조 지역성**: 최근 또는 반복 참조한 페이지를 가까운 미래에 다시 사용할 가능성이 높은 성질이다.
- **참조 이력**: 적재 순서•최근 참조 시각•횟수•참조 비트 등 교체 판단에 쓰는 정보이다.
- **더티 페이지**: 메모리에서 수정돼 퇴출 전에 후면 저장소에 기록해야 하는 페이지이다.
- **교체 예측력**: 참조 이력으로 미래 재사용 여부를 구분하는 정확도이다.
- **갱신 비용**: 참조 이력을 메모리 접근마다 유지하는 처리 부담이다.

</details>

- **참조 지역성 이력**으로 재사용 가능성이 낮은 희생 페이지를 선택한다.
- 정교한 이력을 사용할수록 **교체 예측력과 갱신 비용** 동시 증가한다.
- 참조 순서에 따라 폴트 수가, 더티 비율에 따라 저장장치 쓰기가 증가한다.

#### 한줄 요약

- 참조 이력을 자세히 추적할수록 희생 페이지 예측은 정확해지지만 이력 저장과 갱신 비용도 증가한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **상주 프레임 집합**: 현재 프로세스의 페이지가 적재된 물리 프레임 묶음이다.
- **교체 선택기**: 정책과 참조 이력에 따라 희생 페이지를 결정하는 운영체제 구성요소이다.
- **후면 저장소**: 비상주 페이지를 보관하고 더티 페이지를 기록하는 저장장치 영역이다.
- **저장소 I/O**: 더티 페이지를 기록하고 요청 페이지를 물리 프레임으로 읽어 오는 입출력이다.

</details>

```text
페이지 교체 구조
├─ 상주 프레임 집합
├─ 참조 이력
├─ 교체 선택기
└─ 저장소 I/O
```

가지의 의미: 희생 프레임 판단과 저장소 처리의 정적 책임 구성이다.

| 구성요소 | 책임 |
|:---|:---|
| 상주 프레임 집합 | 현재 페이지•더티 상태 제공 |
| 참조 이력 | 적재•최근•횟수•비트 판단 근거 제공 |
| 교체 선택기 | 정책에 따른 **희생 페이지** 결정 |
| 저장소 I/O | 더티 기록과 요청 페이지 적재 |

#### 한줄 요약
- 프레임과 참조 이력으로 희생 페이지를 고르고 저장소 I/O가 변경분 기록과 새 페이지 적재를 수행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **페이지 폴트 처리기**: 비상주 접근을 받아 프레임 확보•페이지 적재•매핑 갱신을 수행하는 운영체제 루틴이다.
- **프레임 매핑**: 가상 페이지와 물리 프레임의 대응 관계이다.
- **원자 갱신**: 중간의 불일치 상태가 외부에 보이지 않도록 PTE와 프레임 정보를 한 단위로 변경하는 처리이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령을 실행하는 장치이다.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 접근 권한 검사를 담당하는 장치이다.
- **명령 재시작**: 페이지 적재와 매핑 갱신이 끝난 뒤 폴트를 일으킨 메모리 접근을 다시 실행하는 동작이다.

</details>

```text
비상주 페이지 폴트
        │
        ▼
1. 프레임 상태 요청
        │
        ▼
   빈 프레임 판정
        ├─ 있음: 사용 가능한 프레임 할당
        └─ 없음
           └─ 2. 희생 프레임 지정
              └─ 더티 판정
                 ├─ 예: 3. 수정 페이지 전달
                 └─ 아니오: 즉시 재사용
        │
        ▼
4. 요청 페이지 적재
        │
        ▼
5. 매핑 갱신·명령 재시작
```

### 동작 원리

1. **페이지 폴트 처리기**: CPU의 메모리 접근에서 MMU가 비상주 상태를 발견하면 빈 물리 프레임 존재 여부를 확인한다.
2. **희생 페이지**: 빈 프레임이 없으면 참조 이력과 교체 정책으로 퇴출 페이지를 결정한다.
3. **더티 페이지**: 희생 페이지가 수정된 상태이면 변경 내용을 후면 저장소에 기록한다.
4. **저장소 I/O**: 후면 저장소에서 요청 페이지를 읽어 확보한 프레임에 저장한다.
5. **원자 갱신·명령 재시작**: PTE와 프레임 매핑을 한 단위로 갱신한 뒤 중단된 접근을 재실행한다.

#### 한줄 요약

- 빈 프레임이 없으면 참조 이력으로 희생 페이지를 선택하고, 더티 페이지 기록과 새 페이지 적재 후 매핑을 갱신한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **최적(Optimal, OPT)**: 미래에 가장 늦게 참조될 페이지를 퇴출하는 정책이다.
- **선입선출(First-In First-Out, FIFO)**: 가장 먼저 적재된 페이지를 퇴출하는 정책이다.
- **최소 최근 사용(Least Recently Used, LRU)**: 가장 오래 참조하지 않은 페이지를 퇴출하는 정책이다.
- **최소 빈도 사용(Least Frequently Used, LFU)**: 참조 횟수가 가장 적은 페이지를 퇴출하는 정책이다.
- **벨라디 이상**: FIFO에서 프레임 수를 늘렸는데도 페이지 폴트가 증가할 수 있는 현상이다.
- **오프라인 최적 폴트**: 전체 미래 참조열을 알고 계산한 OPT의 최소 폴트 수로 정책의 비교 기준이다.
- **추적 비용**: 적재 순서•최근성•참조 횟수를 교체 판단에 쓰기 위해 기록하고 갱신하는 비용이다.
- **시간 지역성**: 최근 참조한 페이지를 가까운 미래에 다시 사용할 가능성이 높은 접근 특성이다.
- **반복 빈도**: 일정 기간 페이지가 참조된 횟수로 장기적으로 자주 쓰는 페이지를 구분하는 기준이다.
- **미래 참조**: 현재 시점 뒤에 페이지가 다시 사용되는 시점이다.
- **적재 순서**: 페이지가 물리 프레임에 들어온 시간의 선후 관계이다.
- **최근 참조**: 현재 시점에서 가장 가까운 과거의 페이지 접근이다.
- **참조 횟수**: 일정 구간에서 페이지에 접근한 누적 횟수이다.

</details>

| 페이지 교체 정책 | OPT | FIFO | LRU | LFU |
|:---|:---|:---|:---|:---|
| 적용 기준 | **오프라인 최적 폴트** 기준 | 최소 **추적 비용** | 강한 **시간 지역성** | 안정적 **반복 빈도** |
| 핵심 특징 | 가장 늦은 **미래 참조** | 가장 이른 **적재 순서** | 가장 오래된 **최근 참조** | 가장 낮은 **참조 횟수** |
| 한계 | **미래 참조** 확인 불가 | **벨라디 이상** | **최근성 갱신 비용** | 과거 횟수 잔존 |

> 요약: 미래 참조를 아는 OPT를 기준으로 **추적 비용과 지역성**에 맞는 정책을 선택한다.

#### 한줄 요약

- OPT의 최소 폴트 수와 비교해 추적 비용이 낮으면 FIFO, 시간 지역성이 강하면 LRU, 반복 빈도가 안정적이면 LFU를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **Clock 알고리즘**: 참조 비트와 원형 포인터로 최근 사용 페이지를 한 차례 보호하는 LRU 근사이다.
- **재사용 거리**: 같은 페이지의 두 참조 사이에 접근한 서로 다른 페이지 수이다.
- **쓰레싱**: 프레임 부족으로 같은 페이지를 반복 퇴출•재적재하며 I/O가 급증하는 상태이다.
- **백그라운드 기록**: 교체 요청 전에 더티 페이지를 비동기로 저장장치에 기록해 동기 퇴출 지연을 줄이는 기법이다.
- **샘플링**: 일부 시점의 참조만 기록해 이력 갱신 비용을 줄이는 방법이다.
- **카운터 감쇠**: 오래된 참조 횟수의 가중치를 낮춰 과거 편향을 줄이는 방법이다.
- **페이지 테이블 항목(Page Table Entry, PTE)**: 물리 프레임 번호와 상주•권한 상태를 저장하는 항목이다.
- **작업 집합**: 프로세스가 일정 구간에서 반복적으로 참조하는 페이지들의 집합이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워크로드 변화로 기존 정책의 페이지 폴트율 상승 | 정책별 폴트율·**재사용 거리** 비교 | 접근 특성에 맞는 교체 정책 선택 |
| 더티 페이지를 퇴출할 때 동기 쓰기 지연 증가 | 더티 비율에 따라 **백그라운드 기록** 시점 조정 | 교체 경로의 동기 I/O 지연 완화 |
| 정확한 LRU·LFU를 위한 이력 갱신 비용 증가 | **Clock·샘플링·카운터 감쇠** 적용 | 재사용 예측을 유지하며 이력 관리 비용 감소 |
| 프레임이 작업 집합보다 작아 **쓰레싱** 발생 | 프로세스별 **작업 집합**과 프레임 한도 조정 | 같은 페이지의 반복 퇴출·재적재 감소 |
| 퇴출·적재 도중 PTE와 프레임의 매핑 불일치 | **PTE·프레임 매핑 원자 갱신** | 중간 상태 노출 방지로 주소 변환 정확성 확보 |

> Clock은 참조 비트로 **LRU를 저비용 근사**

#### 한줄 요약

- 폴트율•더티 쓰기•이력 비용을 함께 측정하고, Clock의 참조 비트로 최근 페이지를 한 차례 보호한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **정책 선택 기준**: 페이지의 시간 지역성·반복 빈도와 이를 추적하는 비용을 함께 비교하는 판단 기준이다.

</details>

- **정책 선택 기준**에 따라 시간 지역성이 강하면 **LRU•Clock**, 반복 빈도가 안정적이면 **LFU**를 선택한다.

#### 한줄 요약

- 시간 지역성이 강하면 LRU·Clock을, 장기 반복 빈도가 안정적이면 LFU를 선택하되 이력 갱신 비용을 함께 고려한다.
