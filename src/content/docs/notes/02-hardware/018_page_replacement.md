## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지 교체(Page Replacement)**: 요구 페이징 시스템에서 새로운 페이지를 적재할 빈 물리 메모리 프레임이 없을 때, 현재 상주 중인 페이지 중 하나를 축출(Eviction)하여 스왑 영역으로 내보내는 운영체제 메모리 관리 기법.
- **희생 페이지(Victim Page)**: 새 페이지를 물리 메모리에 적재하기 위해 교체 정책에 의해 축출 대상으로 선정된 페이지.
- **페이지 폴트(Page Fault)**: CPU가 참조한 가상 주소의 페이지가 물리 메모리에 존재하지 않아(Present=0) OS 트랩이 발생하는 현상.

</details>

- 정의/개념: 가상 메모리 요구 페이징 환경에서 가용 물리 프레임 고갈 시 미래 참조 가능성이 가장 낮은 **희생 페이지(Victim Page)**를 선정하여 스왑 영역으로 축출하는 **페이지 교체 알고리즘**
- 배경/필요성: 물리 메모리 한계 상황에서 부적절한 희생 페이지 선택 시 **연속적인 페이지 부재 발생 및 시스템 마비(쓰레싱) 초래**

#### 한줄 요약
- 페이지 교체는 물리 메모리가 가득 찼을 때 향후 참조 확률이 가장 낮은 페이지를 내보내어 페이지 폴트율을 최소화하는 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **참조 지역성(Reference Locality)**: 시간적(최근 참조된 데이터 재참조) 및 공간적(인접 주소 연속 참조)으로 메모리가 집중 접근되는 특성.
- **더티 페이지(Dirty Page)**: 메모리에 적재된 후 쓰기(수정)가 발생하여 하위 스왑 디스크의 데이터와 불일치하는 상태의 페이지.
- **벨라디의 모순(Bélády's Anomaly)**: FIFO 교체 알고리즘 등에서 프로세스에 할당된 물리 프레임 수를 늘렸음에도 불구하고 오히려 페이지 폴트 횟수가 증가하는 이상 현상.

</details>

- 지역성 기반 예측: 시간적 **참조 지역성(Temporal Locality)**을 활용하여 최근 사용 이력이 없는 페이지를 우선 축출
- I/O 비용 차등화: **더티 페이지(Dirty Page)** 축출 시에는 디스크 스왑 쓰기(Swap-Out) I/O가 강제되므로 클린 페이지 우선 축출 정책 적용
- 알고리즘 복잡도 절충: 완전한 LRU의 하드웨어/시간적 관리 오버헤드를 완화하기 위해 **Clock(2차 기회)** 등의 근사 알고리즘 활용

#### 한줄 요약
- 시간 지역성을 반영하여 교체 효율을 극대화하되, 실무에서는 하드웨어 관리 비용을 낮춘 Clock 근사 알고리즘을 사용한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **참조 비트(Reference/Accessed Bit)**: 해당 페이지가 CPU에 의해 읽기/쓰기 접근될 때마다 MMU 하드웨어가 자동으로 1로 세팅하는 1비트 상태 플래그.
- **수정 비트(Dirty/Modified Bit)**: 해당 페이지에 쓰기 연산이 수행되었음을 MMU 하드웨어가 1로 표시하는 1비트 플래그.
- **스왑 영역(Swap Space / Backing Store)**: 물리 메모리에서 축출된 희생 페이지의 데이터를 보관하는 보조기억장치(SSD/HDD) 내 전용 저장 파티션.

</details>

```text
[OS 가상 메모리 관리자 (Memory Manager)]
 ├─ [상주 프레임 풀 (Resident Frame Pool)] ─── 물리 메모리 프레임 목록 및 상태
 │
 ├─ [하드웨어 상태 플래그] ────────────────── MMU 지원: 참조 비트(A-bit) + 더티 비트(D-bit)
 │
 ├─ [교체 엔진 (Replacement Engine)] ──────── LRU / Clock(2nd Chance) / Aging 알고리즘
 │
 └─ [스왑 관리 서브시스템 (Swap Manager)] ─── 스왑 인(Swap-In) / 스왑 아웃(Swap-Out) ──► [스왑 파티션 (SSD)]
```

선의 의미: 가지(`├─`, `└─`)는 OS 메모리 서브시스템의 구성요소; 교체 엔진은 MMU의 참조/더티 비트를 읽어 스왑 관리자로 축출을 지시함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **상주 프레임 풀** | OS 커널 메모리 | 현재 물리 메모리에 적재된 활성 페이지 집합 관리 | 프로세스별/전역 프레임 리스트 |
| **참조 비트 (A-bit)**| 페이지 테이블 엔트리(PTE)| 메모리 접근 시 MMU가 1 자동 세팅 | Clock 알고리즘의 판정 기준 |
| **더티 비트 (D-bit)**| 페이지 테이블 엔트리(PTE)| 쓰기 발생 시 MMU가 1 세팅 | 디스크 스왑-아웃 필요 여부 결정 |
| **교체 엔진** | OS 커널 스케줄러 | 정책(LRU/Clock)에 따라 최적의 희생 페이지 선정 | CPU 오버헤드 최소화 설계 |
| **스왑 영역** | 보조기억장치 (SSD) | 메모리 부족 시 축출된 페이지의 임시 백업 저장 | 스왑 디스크 입출력 처리 |

#### 한줄 요약
- 페이지 교체 시스템은 MMU의 참조/더티 비트를 기반으로 교체 엔진이 희생 페이지를 고르고, 스왑 관리자가 디스크 입출력을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스왑 아웃(Swap-Out)**: 메모리에서 희생 페이지를 디스크 스왑 영역에 기록하고 해당 프레임을 비우는 동작.
- **스왑 인(Swap-In)**: 요구된 페이지를 스왑 영역이나 파일 시스템에서 읽어 빈 물리 프레임에 적재하는 동작.

</details>

```text
1. 페이지 폴트 발생 (요청 페이지 미상주)
                      │
                      ▼
2. 물리 메모리 내 가용 빈 프레임 확인
   ┌──────────────────┴──────────────────┐
[ 가용 빈 프레임 존재 ]               [ 가용 빈 프레임 고갈 ]
   │                                     │
   │                                     ▼
   │                             3. 교체 알고리즘(Clock/LRU) 구동 ➔ 희생 페이지 선정
   │                                     │
   │                                     ▼
   │                             4. 희생 페이지의 Dirty 비트 확인
   │                                     ├─ Dirty=1 ➔ 스왑 영역으로 스왑 아웃(Write) 수행
   │                                     └─ Dirty=0 ➔ 디스크 쓰기 생략 (즉시 무효화)
   │                                     │
   │                                     ▼
   │                             5. 희생 페이지 PTE 무효화(Present=0) 및 TLB Invalidate
   └──────────────────┬──────────────────┘
                      │
                      ▼
6. 요청된 새 페이지를 빈 프레임으로 스왑 인(Read)
                      │
                      ▼
7. 새 페이지 PTE 갱신 (Present=1) 및 중단된 명령어 재시작
```

분기 결과: **클린 페이지 축출은** 디스크 쓰기 없이 즉시 프레임을 확보하나, **더티 페이지 축출은** 스왑-아웃 디스크 쓰기 지연이 추가됨

#### 한줄 요약
- 가용 프레임이 없을 때 희생 페이지를 골라 더티일 경우 스왑 아웃한 뒤 새 페이지를 스왑 인하고 명령어를 재개한다.

## Ⅴ. 종류 및 비교

| 알고리즘 | 최적 교체 (OPT) | 선입선출 (FIFO) | 최근 최소 사용 (LRU) | 클록 알고리즘 (Clock / 2nd Chance) |
|:---|:---|:---|:---|:---|
| 선택 기준 | **미래에 가장 오랫동안 사용되지 않을 페이지** | **물리 메모리에 가장 먼저 적재된 페이지** | **과거에 가장 오랫동안 참조되지 않은 페이지** | **참조 비트(0/1)를 원형 큐로 검사하여 기회 부여** |
| 구현 가능성 | 이론적 모델 (미래 참조열 예측 불가로 구현 불가) | 큐(Queue) 자료구조로 단순 구현 가능 | 카운터/스택 하드웨어 지원 필요 (고비용) | **참조 비트 1개로 저비용 구현 (현대 OS 표준)** |
| 장점 | 최저 페이지 폴트율 보장 (성능 상한선) | 오버헤드 극소화 | 높은 시간 지역성 반영, 최우수 성능 | **LRU 성능에 근접하면서 CPU 오버헤드 최소화** |
| 한계 | 실제 시스템 적용 불가 (비교 벤치마크용) | **벨라디의 모순(Bélády's Anomaly) 발생 위험** | 타임스탬프 갱신 오버헤드로 순수 구현 부담 | 최악의 경우 전체 원형 큐 순회 오버헤드 |

#### 한줄 요약
- OPT는 이론적 상한선이고, 순수 LRU는 오버헤드가 크므로, 현대 운영체제는 참조 비트를 활용한 Clock 알고리즘을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카운터 감쇠(Aging Mechanism)**: 주기적으로 참조 비트를 오른쪽으로 시프트하여 과거 참조의 가중치를 점진적으로 낮추는 근사 LRU 기법.
- **백그라운드 페이지 회수(Page Daemon / kswapd)**: 가용 메모리가 임계치(Watermark) 이하로 떨어지면 백그라운드 스레드가 사전에 희생 페이지를 선별해 비동기로 스왑 아웃하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순수 LRU의 타임스탬프 기록으로 인한 CPU/메모리 부하 | **Clock 알고리즘 및 Aging 시프트 레지스터** 적용 | 1클록 내 참조 비트 검사 및 LRU 근사 달성 |
| FIFO 정책에서 프레임 확장 시 페이지 폴트 증가 현상 | **스택 알고리즘(LRU/LFU/Clock)** 및 워킹셋 정책 적용 | 벨라디의 모순 원천 제거 및 예측성 향상 |
| 동기식 스왑 아웃으로 인한 프로세스 블로킹 지연 | **비동기 백그라운드 페이지 데몬(kswapd)** 운용 | 항상 가용 프레임 풀을 유지하여 즉시 할당 보장 |

#### 한줄 요약
- 실무에서는 Clock 알고리즘과 비동기 페이지 회수 데몬(kswapd)을 결합하여 교체 지연을 최소화한다.

## Ⅶ. 결론

- 가상 메모리 요구 페이징의 성능을 보장하기 위해 **이론적 기준인 OPT를 토대로 시간 지역성을 근사하는 Clock(2차 기회) 알고리즘을 OS 커널에 표준 구현**하고, 디스크 I/O 병목을 완화하기 위해 **비동기 백그라운드 페이지 회수(kswapd)와 더티 페이지 배치 쓰기**를 적용하며, 메모리 과다 경합 시 **워킹셋 기반 프레임 할당**을 통해 쓰레싱을 방지하는 메모리 서브시스템 아키텍처 확립

#### 한줄 요약
- 페이지 교체는 Clock 알고리즘과 비동기 회수 데몬의 결합으로 구현되며, 워킹셋 관리가 시스템 안정성의 핵심이다.
