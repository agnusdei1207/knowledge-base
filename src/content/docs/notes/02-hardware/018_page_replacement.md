## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지 교체(Page Replacement)**: 물리 메모리가 가득 차 새로운 페이지를 적재할 공간이 없을 때, 물리 메모리 상의 기존 페이지 중 희생 페이지를 선택하여 축출하는 알고리즘이다.
- **희생 페이지(Victim Page)**: 새로 요청된 페이지를 적재할 프레임 공간을 확보하기 위해 축출 대상으로 선택되는 페이지이다.
- **페이지 폴트(Page Fault)**: 접근하려는 가상 페이지가 물리 메모리에 없어 운영체제가 적재를 시도하는 예외 트랩이다.
- **입출력(Input/Output)**: 희생 페이지 축출 시 디스크 스왑 영역으로 덮어쓰고, 신규 페이지를 읽어 들이는 저장장치 대기 작업이다.

</details>

- 정의: 물리 메모리가 포화 상태일 때 **희생 페이지**를 축출하고 신규 페이지를 적재하는 **페이지 교체** 기법
- 배경: 잘못된 페이지 교체로 인한 잦은 **페이지 폴트**와 디스크 **입출력** 폭증 현상을 방지하기 위함

#### 한줄 요약

- 물리 프레임 포화 시 미래 재참조 확률이 가장 적은 희생 페이지를 선택 축출하여 폴트 발생 비율을 최소화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **참조 지역성(Reference Locality)**: 최근 참조된 페이지가 가까운 미래에 다시 참조되는 시간적 지역성 및 근접 주소가 참조되는 공간적 지역성이다.
- **참조 이력(Reference History)**: 관리자가 희생 페이지를 결정하기 위해 보관하는 접근 시각, 횟수, 적재 순서, 참조 비트 데이터이다.
- **더티 페이지(Dirty Page)**: 메모리 상에서 값이 변경되어 축출될 때 반드시 스왑 영역으로 저장되어야 하는 페이지이다.
- **교체 예측력(Replacement Prediction Accuracy)**: 참조 이력을 바탕으로 향후 불필요할 희생 페이지를 정확히 집어내는 예측 확률이다.

</details>

- **참조 지역성** 정보를 기반으로 미래 재참조 가능성이 가장 낮은 희생 페이지를 선택함.
- 알고리즘이 정교할수록 **교체 예측력**은 상향되나 매 참조마다 갱신하는 하드웨어 비용이 증가함.
- 축출 대상이 **더티 페이지**일 경우 단순 파기가 아닌 스왑 영역에 기록하는 입출력 오버헤드가 추가됨.

#### 한줄 요약

- 지역성을 반영하여 희생 페이지를 선정하며, 알고리즘 정밀도와 하드웨어 갱신 오버헤드 간에 상충 관계가 존재한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상주 프레임 집합(Resident Frame Set)**: 현재 물리 프레임에 적재되어 유효하게 구동 중인 가상 페이지들의 목록이다.
- **후면 저장소(Backing Store)**: 물리 메모리에서 축출된 페이지나 미상주 페이지 데이터를 저장 보관하는 디스크 스왑 영역이다.
- **저장소 입출력(Storage I/O)**: 변경된 축출 페이지의 쓰기 및 신규 요청 페이지의 읽기를 처리하는 데이터 이동 경로이다.

</details>

```text
[ 물리 메모리 프레임 집합 및 참조 이력 관리 ]
                   │
                   ▼
     [ 페이지 교체 알고리즘 엔진 구동 ]
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
[ 변경된 희생 페이지 ] [ 변경 없는 희생 페이지 ]
       │                       │
       ▼                       ▼
 [ 후면 저장소 쓰기 ]      [ 즉시 파기 ]
       │                       │
       └───────────┬───────────┘
                   ▼
       [ 신규 요청 페이지 적재 ]
```

| 구성요소 | 책임 |
|:---|:---|
| 상주 프레임 집합 | 물리 프레임에 적재된 페이지 목록과 유효 상태 관리 |
| 참조 이력 매핑 | 페이지 교체를 위한 시각 및 횟수, 참조 비트 추적 기록 |
| 교체 선택기 | 적용된 알고리즘 정책에 따라 축출할 희생 프레임 결정 |
| **저장소 입출력** | 변경된 희생 페이지 저장 및 신규 요청 페이지 적재 수행 |

#### 한줄 요약

- 상주 프레임 관리자와 교체 선택기, 저장소 입출력 장치가 연동하여 빈 프레임을 확보하고 교체를 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트 처리기(Page Fault Handler)**: 비상주 페이지 접근 예외 시 물리 프레임 확보 및 페이지 교체를 총괄하는 커널 루틴이다.
- **원자 갱신(Atomic Update)**: 희생 페이지 축출 및 신규 적재 시 중간 불일치 상태가 타 스레드에 노출되지 않도록 테이블을 원자적으로 수정하는 연산이다.

</details>

```text
[ 비상주 페이지 폴트 발생 ]
            │
            ▼
     [ 빈 프레임 점검 ]
            │
      ┌─────┴─────┐
      ▼           ▼
[ 프레임 없음 ] [ 빈 공간 ]
      │           │
      ▼           │
[ 희생 페이지 선정 ] │
      │           │
      ▼           │
[ 저장 및 파기 ]   │
      │           │
      └─────┬─────┘
            ▼
    [ 신규 페이지 적재 ]
            │
            ▼
 [ 원자 갱신 및 명령 재시작 ]
```

### 동작 원리

1. 프레임 점검: 빈 프레임이 없으면 교체 선택기를 구동하여 빈 공간 확보를 준비함.
2. 희생 페이지 선정: 지속적으로 관리 중인 참조 이력으로 축출할 희생 프레임을 결정함.
3. 입출력 처리: 변경 상태를 확인하여 필요 시 스왑 영역에 저장하고 즉시 파기함.
4. 페이지 적재 및 갱신: 신규 페이지를 빈 공간에 적재하고 **원자 갱신**과 명령 재시작을 수행함.

#### 한줄 요약

- 빈 프레임 확인 후 희생 페이지를 선택하고 저장소 입출력을 거쳐 신규 페이지를 적재한 뒤 테이블을 갱신한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **최적 교체(Optimal)**: 미래에 가장 오랫동안 사용되지 않을 페이지를 쫓아내는 이론상 최상의 교체 알고리즘이다.
- **선입선출(First-In First-Out)**: 메모리에 가장 먼저 적재된 페이지를 순서대로 축출하는 단순 알고리즘이다.
- **최소 최근 사용(Least Recently Used)**: 가장 오랫동안 참조되지 않은 페이지를 축출하는 시간 지역성 기반 알고리즘이다.
- **최소 빈도 사용(Least Frequently Used)**: 과거 참조 횟수가 가장 적은 페이지를 축출하는 빈도 기반 알고리즘이다.
- **벨라디의 이상(Bélády's Anomaly)**: 프레임 수를 늘려주었음에도 오히려 페이지 폴트 횟수가 늘어나는 아노말리 현상이다.

</details>

| 교체 알고리즘 | 최적 교체 | 선입선출 | 최소 최근 사용 | 최소 빈도 사용 |
|:---|:---|:---|:---|:---|
| 희생 판단 기준 | 미래에 가장 늦게 참조될 페이지 | 가장 먼저 적재된 페이지 | 가장 오래전 참조된 페이지 | 과거 참조 횟수가 가장 적은 페이지 |
| 실현 가능성 | 불가능함 | 큐 구조를 통해 구현 가능함 | 타임스탬프 하드웨어로 가능함 | 참조 카운터를 통해 구현 가능함 |
| 페이지 폴트율 | 이론상 가장 낮음 | 매우 높음 | 지역성을 반영하여 상대적으로 낮음 | 초기 대량 참조 잔존으로 보통 |
| 이상 현상 발생 | 발생 안 함 | **벨라디의 이상** 발생 | 발생 안 함 | 발생 안 함 |

#### 한줄 요약

- 이론상 최상인 최적 교체와 달리 실제로는 지역성을 반영하는 최소 최근 사용 및 카운터 방식이 대중적으로 채택된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **클록 알고리즘(Clock Algorithm)**: 막대한 타임스탬프 갱신 오버헤드를 줄이기 위해 참조 비트와 원형 큐 포인터로 2차 기회를 부여하는 근사 하드웨어 알고리즘이다.
- **백그라운드 기록(Background Writeback)**: 교체 대기 지연을 줄이도록 더티 페이지를 백그라운드 스레드가 미리 저장하는 기술이다.
- **카운터 감쇠(Counter Decay)**: 초기 대량 참조 페이지가 퇴출되지 않는 문제를 막기 위해 주기적으로 카운터를 반감시키는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 사용 갱신 비용에 따른 막대한 하드웨어 전력 소모 및 병목 | 1비트 참조 비트 기반 **클록 알고리즘** 하드웨어 적용 | 관리 오버헤드 극소화 및 유사 교체 성능 보장 |
| 선입선출 적용 시 메모리를 늘려도 폴트가 늘어나는 **벨라디의 이상** | 최소 최근 사용 및 스택 속성의 **클록 알고리즘** 적용 | 비정상적인 폴트 급증 이상 현상 원천 차단 |
| 빈도 사용 시 과거에 참조된 초기 데이터가 퇴출되지 않는 현상 | 일정 시간 주기로 동작하는 **카운터 감쇠** 연동 | 최신 지역성 반영 및 오래된 데이터 메모리 오염 방지 |
| 변경 페이지 축출 시 디스크 입출력으로 인한 명령어 처리 정지 | 운영체제 커널 차원의 비동기 **백그라운드 기록** 가동 | 페이지 교체 시 동기적 입출력 대기 시간 완벽 은닉 |

#### 한줄 요약

- 클록 알고리즘으로 전력 소모를 줄이고 카운터 감쇠와 백그라운드 기록으로 교체 성능과 응답 지연을 최적화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **페이지 교체 선택 기준(Page Replacement Selection Criteria)**: 대상 시스템 워크로드의 참조 지역성 편향, 갱신 비용, 동기 지연 한계를 평가하여 엔진을 선정하는 평가 지표이다.

</details>

- 갱신 관리 비용이 크면 **클록 알고리즘**, 참조 편향이 잦으면 감쇠가 포함된 빈도 교체 정책을 채택함

#### 한줄 요약

- 작업 지역성 특성과 저장장치 입출력 지연 한계를 기준으로 하드웨어 자원을 극대화할 수 있는 교체 정책을 결정해야 한다.
