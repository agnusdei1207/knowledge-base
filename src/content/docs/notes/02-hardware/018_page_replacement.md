## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지 교체(Page Replacement)**: 빈 물리 프레임이 없을 때 기존 상주 페이지를 내보내고 새 페이지를 적재하는 운영체제 기능입니다.
- **희생 페이지(Victim Page)**: 새 페이지를 위해 물리 메모리에서 축출되는 페이지입니다.
- **페이지 폴트(Page Fault)**: 요청 페이지가 비상주해 운영체제 처리가 필요한 예외입니다.

</details>

- 정의/개념: 가상 메모리 관리 환경에서 물리 메모리 프레임 부족 시 메모리에서 내보낼 **희생 페이지(Victim Page)** 를 결정하는 운영체제 스케줄링 알고리즘
- 배경/필요성: 물리 메모리 부족 시 적절한 교체 없이는 **빈번한 페이지 부재 및 쓰레싱(Thrashing) 발생**

#### 한줄 요약

- 메모리가 가득 찼을 때 다시 쓸 가능성이 가장 낮은 페이지를 내보내 다음 페이지가 들어올 자리를 만드는 문제입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **참조 지역성(Reference Locality)**: 최근 사용한 페이지나 가까운 주소가 다시 사용될 가능성이 높은 성질입니다.
- **더티 페이지(Dirty Page)**: 메모리에서 수정되어 저장장치 또는 파일에 최신 값이 아직 반영되지 않은 페이지입니다.
- **벨라디의 모순(Bélády's Anomaly)**: 일부 교체 정책에서 프레임을 늘려도 페이지 폴트가 증가하는 현상입니다.

</details>

- 지역성을 보존하는 **참조 이력 기반 선택**
- 더티 페이지 축출에 따른 **저장장치 쓰기 비용**
- 정책별 폴트율과 **관리 오버헤드 절충**

#### 한줄 요약

- 좋은 정책은 다시 쓸 페이지를 남기지만, 그 판단을 정밀하게 할수록 참조 이력을 기록하고 관리하는 비용도 커집니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상주 프레임 집합(Resident Frame Set)**: 현재 물리 메모리에 적재되어 실행에 사용되는 페이지들의 집합입니다.
- **참조 비트(Reference Bit)**: 페이지가 최근 참조되었는지 나타내는 하드웨어 또는 운영체제 상태 비트입니다.
- **후면 저장소(Backing Store)**: 메모리에서 축출된 페이지를 보관하는 스왑 또는 파일 저장 영역입니다.

</details>

```text
[페이지 교체 관리]
├─ 상주 프레임 집합
├─ 참조 이력·참조 비트
├─ 교체 선택기
└─ 후면 저장소
```

| 구성요소 | 책임 |
|:---|:---|
| 상주 프레임 집합 | 현재 적재 페이지와 유효 상태 관리 |
| 참조 이력·참조 비트 | 페이지 사용 시점과 빈도 기록 |
| 교체 선택기 | 정책에 따른 희생 페이지 결정 |
| 후면 저장소 | 더티 페이지 저장과 새 페이지 공급 |

#### 한줄 요약

- 운영체제는 현재 메모리에 있는 후보와 사용 흔적을 보고 내보낼 페이지를 고른 뒤, 필요한 경우 저장장치와 데이터를 교환합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스왑 아웃(Swap-Out)**: 희생 페이지를 저장장치로 내보내는 처리입니다.
- **스왑 인(Swap-In)**: 필요한 페이지를 저장장치에서 물리 메모리로 가져오는 처리입니다.

</details>

```text
[1. 페이지 폴트]
          │
          ▼
[2. 빈 프레임 확인]
          │
          ├─ 있음 → [4. 새 페이지 적재]
          │
          └─ 없음 → [3. 희생 페이지 선택·축출]
                              │
                              ▼
                         [4. 새 페이지 적재]
```

**동작 원리**
1. **페이지 폴트**: 요청 페이지가 메모리에 없음을 확인
2. **빈 프레임 확인**: 즉시 적재할 빈 물리 프레임 탐색
3. **희생 페이지 선택·축출**: 정책으로 대상을 고르고 더티면 저장
4. **새 페이지 적재**: 후면 저장소에서 읽어 페이지 테이블 갱신

#### 한줄 요약

- 빈자리가 있으면 바로 채우고, 없으면 덜 쓸 페이지를 골라 내보낸 뒤 새 페이지를 적재합니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OPT(Optimal)**: 미래의 페이지 참조를 미리 알고 가장 나중에 사용될 페이지를 교체하는 이론적 최적 알고리즘.
- **FIFO(First-In First-Out)**: 메모리에 가장 먼저 들어온 페이지를 먼저 축출하는 선입선출 알고리즘.
- **LRU(Least Recently Used)**: 가장 최근에 참조되지 않은 페이지를 희생 페이지로 선정하는 시간 지역성 기반 알고리즘.
- **Clock(2차 기회)**: 참조 비트 1개로 원형 큐를 순회하며 LRU를 근사하는 저비용 알고리즘.

</details>

| 교체 알고리즘 | OPT | FIFO | LRU | Clock |
|:---|:---|:---|:---|:---|
| 적용 기준 | 미래 참조열을 아는 이론 비교 | 가장 먼저 적재한 페이지 우선 | 가장 오래 참조하지 않은 페이지 우선 | 참조 비트로 LRU 근사 |
| 핵심 특징 | 최소 폴트의 이상적 기준 | 큐 기반의 단순 구현 | 시간 지역성 반영 | 낮은 관리 비용의 근사 정책 |
| 한계 | 미래를 몰라 실제 구현 불가 | 벨라디의 모순 가능 | 참조 이력 관리 비용 | 정확한 LRU보다 판단 정밀도 낮음 |

#### 한줄 요약

- OPT는 기준선이고, 실제 운영체제는 정확한 LRU의 비용을 피하기 위해 FIFO나 Clock 같은 근사 정책을 선택합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카운터 감쇠(Counter Aging)**: 오래된 참조 빈도의 영향이 줄도록 사용 횟수 가중치를 시간에 따라 낮추는 방식입니다.
- **비동기 회수(Asynchronous Reclaim)**: 메모리 부족 전에 백그라운드로 페이지를 회수해 급한 대기를 줄이는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 교체 이력 관리가 CPU·전력 비용 증가 | 참조 비트 기반 Clock 적용 | 선택 오버헤드와 폴트율 균형 |
| FIFO에서 프레임 증가에도 폴트 증가 | LRU 근사와 작업 집합 기준 정책 적용 | 지역성 보존과 예측 가능성 향상 |
| LFU가 오래된 고빈도 페이지를 고정 | 카운터 감쇠와 최근성 결합 | 현재 작업 집합 반영 |
| 더티 축출이 저장장치 지연 유발 | 비동기 회수와 백그라운드 기록 적용 | 동기 페이지 폴트 지연 완화 |

#### 한줄 요약

- 운영체제는 가장 정교한 정책보다 실제 지역성을 보존하면서도 참조 기록과 저장장치 대기를 감당할 수 있는 정책을 선택합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **쓰레싱(Thrashing)**: 페이지 교체와 저장장치 입출력이 실행보다 많아져 시스템 처리량이 급락하는 상태입니다.

</details>

- 실무 운영체제는 **Clock(LRU 근사)**, 이론적 성능 한계 분석은 **OPT** 선택

#### 한줄 요약

- 페이지 교체의 목표는 폴트 수만 줄이는 것이 아니라, 페이지를 고르는 비용과 더티 데이터를 저장하는 비용까지 포함해 실제 실행을 안정시키는 것입니다.
