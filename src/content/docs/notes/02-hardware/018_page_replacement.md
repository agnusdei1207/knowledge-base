## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지 교체(Page Replacement)**: 요구 페이징 시스템에서 새로운 페이지를 적재할 빈 물리 메모리 프레임이 없을 때, 현재 상주 중인 페이지 중 하나를 축출(Eviction)하여 스왑 영역으로 내보내는 운영체제 메모리 관리 기법.
- **희생 페이지(Victim Page)**: 새 페이지를 물리 메모리에 적재하기 위해 교체 정책에 의해 축출 대상으로 선정된 페이지.
- **페이지 폴트(Page Fault)**: CPU가 참조한 가상 주소의 페이지가 물리 메모리에 존재하지 않아(Present=0) OS 트랩이 발생하는 현상.

</details>

- 정의/개념: 가상 메모리 요구 페이징 환경에서 가용 물리 프레임 고갈 시 미래 참조 가능성이 가장 낮은 **희생 페이지**(Victim Page)를 선정하여 스왑 영역으로 축출하는 메모리 관리 알고리즘
- 배경/필요성: 요구 페이징 환경에서 가용 물리 프레임 고갈 시 부적절한 페이지 축출로 발생하는 **반복적 스왑 I/O 및 쓰레싱(Thrashing) 병목 위험**

#### 한줄 요약
- 페이지 교체는 물리 메모리가 가득 찼을 때 향후 참조 확률이 가장 낮은 페이지를 내보내어 페이지 폴트율을 최소화하는 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **참조 지역성(Reference Locality)**: 시간적(최근 참조된 데이터 재참조) 및 공간적(인접 주소 연속 참조)으로 메모리가 집중 접근되는 특성.
- **더티 페이지(Dirty Page)**: 메모리에 적재된 후 쓰기(수정)가 발생하여 하위 스왑 디스크의 데이터와 불일치하는 상태의 페이지.
- **벨라디의 모순(Bélády's Anomaly)**: FIFO 교체 알고리즘 등에서 프로세스에 할당된 물리 프레임 수를 늘렸음에도 불구하고 오히려 페이지 폴트 횟수가 증가하는 이상 현상.

</details>

- 시간적 **참조 지역성**(Temporal Locality)을 활용하여 최근 사용 이력이 없는 페이지 우선 축출
- **더티 페이지**(Dirty Page) 축출 시 디스크 스왑 쓰기 I/O가 수반되므로 클린 페이지 우선 축출
- 완전 LRU의 관리 오버헤드를 완화하기 위해 **Clock**(2차 기회) 근사 알고리즘 활용

#### 한줄 요약
- 시간 지역성을 반영하여 교체 효율을 극대화하되, 실무에서는 하드웨어 관리 비용을 낮춘 Clock 근사 알고리즘을 사용한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **참조 비트(Reference/Accessed Bit)**: 해당 페이지가 CPU에 의해 읽기/쓰기 접근될 때마다 MMU 하드웨어가 자동으로 1로 세팅하는 1비트 상태 플래그.
- **수정 비트(Dirty/Modified Bit)**: 해당 페이지에 쓰기 연산이 수행되었음을 MMU 하드웨어가 1로 표시하는 1비트 플래그.
- **스왑 영역(Swap Space / Backing Store)**: 물리 메모리에서 축출된 희생 페이지의 데이터를 보관하는 보조기억장치(SSD/HDD) 내 전용 저장 파티션.

</details>

```text
페이지 교체 서브시스템 (Page Replacement Subsystem)
 ├─ 가상 메모리 관리자 (Memory Manager)
 │   ├─ 상주 프레임 풀 (Resident Frame Pool)
 │   └─ 교체 엔진 (Clock / LRU Replacement Engine)
 ├─ MMU 하드웨어 상태 플래그
 │   ├─ 참조 비트 (Accessed Bit)
 │   └─ 수정 비트 (Dirty Bit)
 └─ 스왑 관리자 (Swap Subsystem)
     └─ 스왑 영역 (Swap Space: SSD/NVMe)
```

선의 의미: 가지(`├─`, `└─`)는 OS 메모리 서브시스템과 하드웨어 제어 플래그의 계층 포함 관계

| 구성요소 | 책임 |
|:---|:---|
| 상주 프레임 풀 | 물리 메모리에 적재된 페이지 집합 관리 |
| 참조 비트 | 접근 이력을 표시해 **Clock** 판정 지원 |
| 더티 비트 | 수정 여부로 **스왑 아웃** 필요성 판정 |
| 교체 엔진 | 정책에 따라 희생 페이지 선정 |
| 스왑 영역 | 축출된 페이지의 보조기억장치 보관 |

#### 한줄 요약
- 페이지 교체 시스템은 MMU의 참조/더티 비트를 기반으로 교체 엔진이 희생 페이지를 고르고, 스왑 관리자가 디스크 입출력을 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스왑 아웃(Swap-Out)**: 메모리에서 희생 페이지를 디스크 스왑 영역에 기록하고 해당 프레임을 비우는 동작.
- **스왑 인(Swap-In)**: 요구된 페이지를 스왑 영역이나 파일 시스템에서 읽어 빈 물리 프레임에 적재하는 동작.

</details>

```text
페이지 폴트 트랩 발생 (요청 페이지 미상주)
       │
       ▼
1. 가용 프레임 확인
       │
       ├─ 가용 프레임 존재 ──► 4. 요청 페이지 스왑 인
       │
       └─ 가용 프레임 고갈
              │
              ▼
       2. 희생 페이지 선정
              │
              ▼
       3. 더티 비트 검사·축출
              │
              ├─ Dirty=1 ──► 스왑 영역에 기록
              │
              └─ Dirty=0 ──► 디스크 쓰기 생략 및 즉시 프레임 회수
              │
              ▼
       4. 요청 페이지 스왑 인
              │
              ▼
       5. 매핑 갱신·명령어 재시작
```

분기 결과: **클린 페이지** 축출은 디스크 쓰기 생략으로 즉시 완료, **더티 페이지** 축출은 스왑 아웃 디스크 쓰기 지연 수반

**동작 원리**

1. **가용 프레임 확인**: 빈 프레임 존재 여부 판정
2. **희생 페이지 선정**: 교체 정책으로 축출 대상 선택
3. **더티 비트 검사·축출**: 수정 페이지는 기록 후 프레임 회수
4. **요청 페이지 스왑 인**: 요구 페이지를 회수 프레임에 적재
5. **매핑 갱신·명령어 재시작**: PTE 갱신 후 접근 재실행

#### 한줄 요약
- 가용 프레임이 없을 때 희생 페이지를 골라 더티일 경우 스왑 아웃한 뒤 새 페이지를 스왑 인하고 명령어를 재개한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 최적 교체 (OPT) | 선입선출 (FIFO) | 최근 최소 사용 (LRU) | 클록 알고리즘 (Clock / 2nd Chance) |
|:---|:---|:---|:---|:---|
| 선택 기준 | 미래에 가장 오랫동안 미사용될 페이지 | 메모리에 가장 먼저 적재된 페이지 | 과거 가장 오랫동안 미참조된 페이지 | **참조 비트**(0/1) 원형 순회 기반 기회 부여 |
| 구현 방식 | 이론적 상한선 모델 (구현 불가) | 큐(Queue) 자료구조 단순 구현 | 하드웨어 타임스탬프/스택 지원 필요 | **참조 비트 1개** 기반 저비용 구현 |
| 장점 | **최저 페이지 폴트율** 보장 | 구현 오버헤드 극소화 | 시간 지역성 반영 우수 | **LRU 근접 성능** 및 CPU 오버헤드 최소화 |
| 한계 | 실제 시스템 적용 불가 (비교 기준) | **벨라디의 모순**(Bélády's Anomaly) 발생 | 타임스탬프 갱신 하드웨어 비용 | 최악의 경우 원형 큐 전체 순회 지연 |

#### 한줄 요약
- OPT는 이론적 상한선이고, 순수 LRU는 오버헤드가 크므로, 현대 운영체제는 참조 비트를 활용한 Clock 알고리즘을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카운터 감쇠(Aging Mechanism)**: 주기적으로 참조 비트를 오른쪽으로 시프트하여 과거 참조의 가중치를 점진적으로 낮추는 근사 LRU 기법.
- **백그라운드 페이지 회수(Page Daemon / kswapd)**: 가용 메모리가 임계치(Watermark) 이하로 떨어지면 백그라운드 스레드가 사전에 희생 페이지를 선별해 비동기로 스왑 아웃하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순수 LRU의 타임스탬프 기록으로 인한 CPU 부하 | **Clock 알고리즘 및 Aging 시프트 레지스터** 적용 | 1클록 내 참조 비트 검사 및 LRU 근사 달성 |
| FIFO 정책에서 프레임 확장 시 페이지 폴트 증가 현상 | **스택 알고리즘**(LRU/LFU/Clock) 적용 | **벨라디의 모순** 원천 제거 및 예측성 향상 |
| 동기식 스왑 아웃으로 인한 프로세스 블로킹 지연 | **비동기 백그라운드 페이지 데몬**(kswapd) 운용 | 상시 가용 프레임 풀 유지로 즉시 할당 보장 |

#### 한줄 요약
- 실무에서는 Clock 알고리즘과 비동기 페이지 회수 데몬(kswapd)을 결합하여 교체 지연을 최소화한다.

## Ⅶ. 결론

- 하드웨어 오버헤드와 적중률의 최적 절충안인 **Clock(2차 기회) 및 다중 큐 활성/비활성 LRU 리스트**가 범용 OS의 표준이며, 최근 초고속 NVMe SSD 및 CXL 메모리 풀링 환경에서는 **계층형 메모리 스왑 티어링(Memory Tiering)**으로 고도화 발전

#### 한줄 요약
- 페이지 교체는 Clock 알고리즘과 비동기 회수 데몬의 결합으로 구현되며, 워킹셋 관리가 시스템 안정성의 핵심이다.
