## Ⅰ. 개요

**전송률(data rate)**은 링크가 단위 시간에 전송하는 심볼·비트·전송 횟수를 말하며, **대역폭**은 문맥에 따라 이론적인 링크 용량 또는 전달 가능한 데이터량을 뜻한다. **실효 처리량(effective throughput)**은 응용 또는 측정 지점에서 실제 전달된 유효 페이로드를 시간으로 나눈 값이다.

GT/s, MT/s, Gb/s, GB/s는 같은 값이 아니다. 또한 단방향 값인지, 송·수신 합산인지, 인코딩 전인지, 패킷 오버헤드 후인지 명확히 해야 수치를 비교할 수 있다.

#### 한줄 요약

- 대역폭 계산은 전송 단위·방향·인코딩·프로토콜 경계를 먼저 정한 뒤 실측 페이로드와 비교한다.

## Ⅱ. 특징

- **심볼률과 비트율**: PAM4처럼 심볼당 여러 비트를 싣는 변조에서는 심볼률과 원시 비트율이 다를 수 있다.
- **레인·버스 폭**: 직렬 링크는 레인 수, 병렬 버스는 유효 데이터 폭과 전송률이 기초 입력이다.
- **인코딩·FEC**: 라인 코딩, 블록 코딩, FEC 등은 원시 링크에서 데이터 전달에 쓸 수 있는 비율을 바꾼다.
- **프로토콜·운영 오버헤드**: 헤더, CRC, 흐름 제어, 재전송, 패킷 크기, 경합, 메모리·소프트웨어 병목이 실효 처리량을 낮출 수 있다.

#### 한줄 요약

- 링크 사양은 상한이고, 페이로드 처리량은 프로토콜과 시스템 동작까지 포함한 결과다.

## Ⅲ. 구조 및 구성요소

```text
응용·DMA 데이터
        │
패킷화·주소·무결성·흐름 제어
        │
링크 계층 재전송·순서 관리
        │
물리 계층: 인코딩·FEC·레인/버스 폭·신호 전송
        │
수신 처리·메모리·응용 소비
        │
측정 지점의 유효 페이로드 처리량
```

| 구성요소 | 역할 |
|:---|:---|
| 송신 큐·DMA | 데이터를 준비하고 메모리·장치 간 이동을 요청한다. |
| 프로토콜 계층 | 주소, 헤더, 무결성, 흐름 제어 정보를 추가한다. |
| 링크 계층 | 순서, 크레딧, 재전송 등 링크별 신뢰성·흐름을 관리할 수 있다. |
| 물리 계층 | 레인·버스 폭, 변조, 인코딩, FEC, 신호 무결성을 담당한다. |
| 수신·소비 경로 | 패킷을 처리해 메모리나 응용에 전달하며, 이 경로도 병목이 될 수 있다. |
| 계측기 | 어떤 계층·방향·시간 창을 측정했는지 명시한 처리량을 기록한다. |

#### 한줄 요약

- 실효 처리량은 물리 링크뿐 아니라 송신 큐에서 수신 소비자까지의 전송 경로가 만든 값이다.

## Ⅳ. 동작 흐름

```text
측정 대상의 단위·방향·계층·시간 창 정의
        ↓
원시 전송률과 유효 레인/버스 폭 확인
        ↓
해당 규격의 인코딩·FEC 효율 반영
        ↓
패킷 크기·헤더·흐름 제어로 페이로드 상한 산정
        ↓
워크로드에서 바이트·시간·재전송·지연을 실측
        ↓
링크·메모리·소프트웨어·경합 구간을 구분해 병목 분석
```

병렬 인터페이스의 단순 상한은 유효 폭 $w$와 전송률 $r$로 다음처럼 쓸 수 있다.

$$
B_{\mathrm{raw}}=\frac{w\times r}{8}
$$

직렬 링크에서 레인당 원시 비트율 $r$, 레인 수 $n$, 물리 데이터 효율 $\eta_{\mathrm{phy}}$를 알면 다음과 같이 나타낼 수 있다.

$$
B_{\mathrm{link}}=\frac{r\times n\times\eta_{\mathrm{phy}}}{8}
$$

패킷별 오버헤드가 일정하다고 단순화하면 $\eta_{\mathrm{proto}}$를 추가로 곱할 수 있다. 실제 효율은 페이로드 크기와 트래픽 패턴에 따라 변하므로 측정으로 검증한다.

#### 한줄 요약

- 산식은 상한 추정용이며, 실제 시스템에서는 패킷 크기·경합·재전송·소비 경로를 측정해야 한다.

## Ⅴ. 비교

| 비교 항목 | 병렬 버스 | 고속 직렬 링크 |
|:---|:---|:---|
| 전송 구조 | 여러 데이터 선을 같은 인터페이스에서 사용 | 독립 차동 레인을 묶어 사용 |
| 동기·신호 과제 | 폭 증가와 타이밍 정렬, 배선 길이 제어 | 클록 복구, 등화, 레인 정렬, SerDes 전력 |
| 대표 적용 | 메모리 채널·짧은 온보드 인터페이스 | 확장 장치·보드 간·패키지 간 인터커넥트 |
| 대역폭 해석 | 전송률·유효 폭·채널 수와 읽기/쓰기 방향 확인 | 레인당 속도·레인 수·인코딩·양방향 표기 확인 |

병렬 버스에도 프로토콜·타이밍 오버헤드가 있고, 직렬 링크에도 규격·세대에 따라 인코딩 방식이 다르다. “병렬은 인코딩 없음, 직렬은 특정 인코딩”으로 일반화하지 않는다.

#### 한줄 요약

- 병렬·직렬 모두 물리 상한과 실제 전달량을 구분하며, 적용 거리·핀·전력·신호 조건으로 선택한다.

## Ⅵ. 실무 고려사항 및 대책

| Problem | Countermeasure | Effect |
|:---|:---|:---|
| Gb/s와 GB/s, 단방향·합산 값을 혼용 | 수치마다 비트/바이트, 한 방향/합산, 계층·효율 포함 여부를 표기 | 사양 비교와 용량 계획의 해석 오류 감소 |
| 명목 링크 속도를 응용 처리량으로 가정 | 실제 패킷 크기·읽기/쓰기 비율·동시성·CPU/DMA 조건에서 벤치마크 | 링크 외 병목과 유효 여유 파악 |
| 인코딩·FEC·헤더·재전송 비용을 누락 | 적용 규격의 프레이밍·오류 처리와 오류율을 반영해 상한·하한을 산정 | 과소 설계·예상 밖 지연 위험 완화 |
| 공유 자원의 경합으로 지연이 커짐 | QoS·큐·중재·트래픽 형상화와 메모리 계층을 함께 관찰 | 중요 트래픽의 지연·처리량 관리 지원 |

#### 한줄 요약

- 단위·방향 표준화와 워크로드 기반 계측이 대역폭 계산의 필수 검증 단계다.

## Ⅶ. 결론

인터커넥트를 선택할 때는 세대명이나 합산 최고 속도보다 필요한 단방향 페이로드, 지연, 패킷 크기, 동시 트래픽, 오류·전력 조건을 먼저 정의한다. 예상 부하가 상한에 가까우면 링크 확장뿐 아니라 메모리·DMA·소프트웨어 병목과 트래픽 정책을 함께 검토한다. 대용량·낮은 지연 요구가 섞인 시스템일수록 계층별 계측으로 설계를 검증한다.

#### 한줄 요약

- 좋은 대역폭 계획은 “최대 속도”가 아니라 정의된 측정 경계의 지속 가능한 페이로드 처리량을 기준으로 한다.
