## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 가상 페이지의 물리 주소 변환 결과를 저장해 페이지 테이블 순회를 줄이는 MMU 캐시.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 가상 주소를 물리 주소로 변환하고 페이지 접근 권한을 검사하는 하드웨어.
- **다단계 페이지 순회(Multi-Level Page Walk)**: 가상 페이지 번호의 각 부분을 이용해 여러 단계의 페이지 테이블을 차례로 조회하는 변환 절차.

</details>

- 정의/개념: **MMU** 내부에서 최근 가상 페이지와 물리 페이지의 대응을 재사용하는 **TLB**
- 배경/필요성: 메모리 접근마다 페이지 테이블을 여러 단계로 순회하면 주소 변환 지연과 메모리 접근 횟수 증가

#### 한줄 요약

- TLB는 최근 주소 변환을 재사용해 데이터 접근 전에 필요한 다단계 페이지 순회를 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리의 프로세스 주소 공간 식별자.
- **TLB 도달 범위(TLB Reach)**: 엔트리 수와 페이지 크기의 곱으로 TLB가 한 번에 덮는 주소 범위.
- **작업 집합(Working Set)**: 프로세스가 현재 반복적으로 접근하는 페이지들의 집합.
- **TLB 엔트리 수(TLB Entry Count)**: TLB에 저장할 수 있는 주소 변환 항목 수.
- **페이지 크기(Page Size)**: TLB 엔트리 하나가 변환하는 연속 주소 범위.
- **접근 권한(Access Permission)**: 페이지별로 읽기·쓰기·실행 허용 여부를 나타내는 보호 정보.

</details>

- 최근 변환 재사용으로 페이지 순회 지연 회피
- 태그·**ASID**·**접근 권한**을 함께 비교해 주소 공간별 변환 보호
- **TLB 엔트리 수**와 **페이지 크기**가 **TLB 도달 범위** 결정

$$
TLB\ Reach = TLB\ Entry\ Count \times Page\ Size
$$

> 단일 페이지 크기의 도달 범위 기본식

#### 한줄 요약

- 작업 집합이 TLB 도달 범위를 넘으면 변환이 계속 축출되므로, TLB 엔트리 수와 페이지 크기가 미스율을 좌우한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **가상 페이지 번호(Virtual Page Number, VPN)**: 가상 주소의 페이지 번호.
- **물리 페이지 번호(Physical Page Number, PPN)**: 변환 결과인 물리 페이지 번호.
- **TLB 엔트리(TLB Entry)**: VPN•ASID와 대응 PPN•권한•유효 상태를 함께 보관하는 항목.
- **페이지 테이블 순회기(Page Table Walker)**: TLB 미스 시 페이지 테이블을 탐색하고 변환을 TLB에 채우는 회로.
- **페이지 테이블 항목(Page Table Entry, PTE)**: PPN과 유효•상주•접근 권한을 담는 항목.
- **TLB 조회기(TLB Lookup Unit)**: 가상 페이지 번호와 ASID를 엔트리 태그와 비교하고 접근 권한을 검사하는 회로.

</details>

```text
TLB 변환 구조
├─ TLB 조회기
├─ TLB 엔트리
└─ 페이지 테이블 순회기
```

가지의 의미: 변환 조회•저장•미스 순회의 정적 책임 구성.

| 구성요소 | 책임 |
|:---|:---|
| TLB 조회기 | **VPN**•**ASID**•권한 비교 |
| TLB 엔트리 | 최근 VPN-PPN 변환 보관 |
| 페이지 테이블 순회기 | PTE 탐색과 엔트리 채움 |

#### 한줄 요약
- 조회기와 엔트리가 최근 변환을 처리하고 미스일 때만 순회기가 페이지 테이블을 탐색한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **TLB 적중(TLB Hit)**: 주소 변환을 TLB에서 즉시 찾은 상태.
- **TLB 미스(TLB Miss)**: 주소 변환을 찾지 못해 페이지 테이블 순회가 필요한 상태.
- **페이지 오프셋(Page Offset)**: 페이지 안의 바이트 위치를 나타내며 주소 변환 없이 유지되는 하위 비트.
- **페이지 폴트(Page Fault)**: 페이지 비상주·미매핑 또는 접근 권한 위반을 운영체제에 알리는 예외.
- **접근 예외(Access Exception)**: 요청한 페이지 접근 권한 위반을 운영체제에 알리는 예외.

</details>

```text
가상 주소•접근 유형
         │
         ▼
1. TLB 엔트리 조회
         │
         ▼
    변환 적중 판정
         ├─ 적중: 물리 주소•권한 반환
         └─ 미스
            └─ 2. VPN•ASID 순회 요청
               └─ 페이지 테이블의 각 단계
                  └─ 3. PTE 주소 전달
                     └─ 다음 단계 주소•PTE로 반복
         │
         ▼
    최종 PTE 판정
         ├─ 유효•상주•허용
         │  └─ 4. 변환•권한 정보 전달
         │     └─ 물리 주소•권한 반환
         └─ 비상주•미매핑•위반
            └─ 페이지 폴트•접근 예외
```

### 동작 원리

1. **TLB 엔트리 조회**: VPN·ASID와 접근 권한이 일치하는 유효 변환 검색.
2. **페이지 테이블 순회 요청**: TLB 미스가 발생한 VPN의 변환 탐색 시작.
3. **PTE 단계별 조회**: VPN의 각 인덱스로 다단계 페이지 테이블을 따라 최종 PTE 확인.
4. **변환·권한 정보 저장**: 유효한 PPN과 접근 권한을 TLB 엔트리에 저장, 변환하지 않은 **페이지 오프셋**을 PPN에 결합해 물리 주소 반환.

#### 한줄 요약

- TLB 적중은 저장된 변환으로 즉시 물리 주소를 만들고, TLB 미스만 페이지 테이블 순회로 변환을 채운다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **페이지 테이블 순회(Page Table Walk)**: 다단계 페이지 테이블을 따라 최종 PTE를 찾는 하드웨어 동작.
- **유효 변환(Valid Translation)**: 현재 주소 공간에서 접근 권한 검사를 통과하며 사용할 수 있는 VPN-PPN 대응.
- **입출력(Input/Output, I/O)**: 저장장치와 메모리 사이의 데이터 전송.

</details>

| 주소 변환 실패 | TLB 미스 | 페이지 폴트 |
|:---|:---|:---|
| 적용 기준 | **페이지 순회**만으로 유효 변환을 찾을 수 있을 때 | 운영체제의 페이지 적재·매핑·권한 처리 필요 시 |
| 핵심 특징 | TLB에 일치 **유효 변환** 부재 | PTE의 비상주•미매핑•보호 위반 |
| 한계 | 미스 반복에 따른 변환 지연 누적 | 비상주 페이지 적재 시 저장장치 **I/O** 대기 |

> 요약: 순회로 메워지면 하드웨어, 못 메우면 운영체제 소관.

#### 한줄 요약

- TLB 미스는 하드웨어 순회로 변환을 채우지만, 페이지 폴트는 운영체제가 적재•매핑•권한을 처리한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **대형 페이지(Huge Page)**: 기본 페이지보다 큰 변환 단위로 엔트리당 도달 범위를 늘리는 페이지.
- **페이지 순회 캐시(Page Walk Cache)**: 상위 단계 PTE를 저장해 TLB 미스의 메모리 접근 수를 줄이는 캐시.
- **선택적 무효화(Selective Invalidation)**: 문맥이나 매핑 변경 시 영향받는 TLB 엔트리만 제거하는 방법.
- **용량 미스(Capacity Miss)**: 작업 집합의 변환 수가 TLB에 들어가지 않아 엔트리가 반복 축출되는 미스.
- **지역성(Locality)**: 가까운 시간이나 주소의 페이지 테이블 항목을 반복 접근하는 성향.
- **내부 단편화(Internal Fragmentation)**: 큰 페이지 안에서 사용하지 못하고 남는 공간이 생기는 현상.
- **외부 단편화(External Fragmentation)**: 큰 페이지에 필요한 연속 물리 메모리 구간을 확보하지 못하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 집합이 **TLB 도달 범위** 초과 | 미스율 측정 후 반복 접근 영역에 **대형 페이지** 적용 | 엔트리당 범위 확대로 **용량 미스** 감소 |
| 문맥 전환마다 TLB 전체 무효화 | **ASID**·**선택적 무효화**로 주소 공간 구분 | 기존 변환 보존으로 전환 후 TLB 미스 감소 |
| 다단계 순회가 메모리 접근 증가로 변환 병목 | **지역성** 이용하는 **페이지 순회 캐시**로 상위 PTE 재사용 | 순회 메모리 접근 감소로 미스 지연 단축 |
| 대형 페이지 할당으로 **내부·외부 단편화** | 적용 대상 선별과 예약량·사용률 감시 | 도달 범위 개선 유지하며 메모리 낭비 제한 |

#### 한줄 요약

- 큰 작업 집합의 반복 접근 영역에 대형 페이지를 적용하면 같은 엔트리 수로 TLB 도달 범위를 넓혀 용량 미스를 줄일 수 있다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **전환 미스(Context Switch Miss)**: 문맥 전환 때 TLB를 비워 새 프로세스의 변환을 다시 채우며 발생하는 미스.

</details>

- 도달 범위 초과는 **대형 페이지**, **전환 미스**는 **ASID** 적용

#### 한줄 요약

- TLB 성능은 작업 집합의 도달 범위 초과와 문맥 전환의 전체 무효화를 구분한 뒤 대형 페이지 또는 ASID를 선택해 개선한다.
