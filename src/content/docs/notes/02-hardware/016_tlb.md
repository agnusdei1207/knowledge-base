## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 가상 주소를 물리 주소로 변환 시 다단계 페이지 테이블 순회를 생략하도록 최근 변환 매핑을 저장하는 고속 캐시.
- **MMU(Memory Management Unit)**: 주소 변환, 캐시 제어, 메모리 보호 및 접근 권한 검사를 총괄하는 하드웨어 블록.
- **다단계 페이지 순회(Multi-Level Page Walk)**: 64비트 가상 메모리에서 PGD/P4D/PUD/PMD/PTE 테이블을 연속 탐색하여 물리 주소를 찾는 과정.

</details>

- 정의/개념: 가상 주소를 물리 주소로 변환할 때 다단계 페이지 테이블 참조 지연을 제거하기 위해 최근 매핑(VPN $\to$ PPN)을 캐싱하는 MMU 내부의 고속 변환 버퍼
- 배경/필요성: 64비트 가상 메모리의 4~5단계 페이지 순회(Page Walk)로 인한 **메모리 참조 지연 병목(최대 4배 추가 메모리 접근) 해소**

#### 한줄 요약

- 가상-물리 주소 변환(VPN $\to$ PPN)을 고속 캐싱하여 **다단계 페이지 순회 지연 제거**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ASID(Address Space Identifier)**: 프로세스별 고유 ID를 엔트리에 태깅하여 문맥 전환(Context Switch) 시 TLB 전체 플러시를 방지하는 기술.
- **TLB Reach**: $\text{TLB Reach} = (\text{TLB Entry Count}) \times (\text{Page Size})$로 계산되는 변환 보장 메모리 커버리지.

</details>

- 최근 주소 변환 결과를 **주소 공간 식별자(ASID)**와 병렬 대조하여 1클록 내 물리 주소 반환
- 프로세스 전환 시 ASID 태깅을 통해 전체 TLB 플러시를 우회하여 문맥 전환 오버헤드 극소화
- **TLB 도달 범위(TLB Reach)**가 작업 집합(Working Set)보다 작을 경우 발생하는 TLB 스래싱 억제

#### 한줄 요약

- **ASID 태깅**으로 플러시 오버헤드를 방지하고 **Huge Page**로 도달 범위 확장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **VPN(Virtual Page Number)**: 가상 주소의 상위 비트로 TLB 태그 비교에 사용되는 식별자.
- **PPN(Physical Page Number)**: 변환 적중 시 출력되는 실제 DRAM 메모리의 프레임 번호.
- **하드웨어 페이지 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 대신해 메모리 내 다단계 페이지 테이블을 자동 순회하는 하드웨어 유닛.

</details>

```text
[ 가상 주소 (Virtual Address) ]
┌───────────────────────────────┬───────────────────────────────┐
│ 가상 페이지 번호 (VPN)        │ 페이지 오프셋 (Offset)        │
└───────────────┬───────────────┴───────────────┬───────────────┘
                │                               │
                ▼                               │
    [ TLB 병렬 태그 비교 (Fully/Set) ]          │
    ├─ [Hit] ──> 물리 페이지 번호 (PPN) 추출    │
    │                      │                    │
    │                      ▼                    ▼
    │           [ 물리 주소 (Physical Address) : PPN + Offset ]
    │
    └─ [Miss] ─> [ 하드웨어 페이지 테이블 워커 (Page Walk) 구동 ]
                       │
                       ▼
                 DRAM 페이지 테이블 탐색 후 TLB 리필 (Refill)
```

선의 의미: 가상 주소(VPN+Offset) 입력부터 TLB 병렬 비교 및 미스 시 하드웨어 페이지 워커 구동 구조도.

| 구성요소 | 책임 |
|:---|:---|
| TLB 조회기 | **가상 페이지 번호**와 **주소 공간 식별자** 및 접근 권한 병렬 비교 |
| TLB 엔트리 배열 | 가상 및 물리 번호 매핑쌍과 상태 비트 저장 보존 |
| 페이지 테이블 순회기 | 미스 발생 시 다단계 테이블 탐색 및 캐시 채우기 자동 수행 |

#### 한줄 요약

- **TLB 엔트리(VPN/PPN/ASID/권한)와 하드웨어 페이지 테이블 워커** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이지 폴트(Page Fault)**: 해당 가상 페이지가 물리 메모리에 매핑되어 있지 않을 때 발생하는 OS 트랩 인터럽트.

</details>

```text
[ CPU 가상 주소 참조 (VPN + Offset) ]
                  │
                  ▼
          [ TLB 조회 (Hit / Miss) ]
                  │
       ┌──────────┴──────────┐
       ▼ [Hit]               ▼ [Miss]
[ PPN + Offset 결합 ]  [ 하드웨어 Page Table Walker 구동 ]
       │                     │
       ▼               ┌─────┴─────┐
[ 물리 메모리 접근 ]   ▼ [Valid]   ▼ [Invalid / Non-present]
                 [ TLB 리필 ]  [ Page Fault 예외 트랩 발생 (OS) ]
                       │             │
                       ▼             ▼
                 [ 물리 주소 반환 ] [ 디스크 Swap-In 및 PTE 갱신 ]
```

**동작 원리**

1. **TLB 조회**: 가상 주소의 VPN과 ASID를 TLB 엔트리들과 병렬 비교
2. **적중 시**: 일치하는 PPN을 즉시 꺼내어 하위 Offset과 결합해 물리 주소 생성 후 1클록 내 완료
3. **미스 시**: 하드웨어 Page Walker가 CR3/TTBR 레지스터를 시작으로 다단계 페이지 테이블 순회
4. **PTE 검증**: 페이지가 메모리에 상주하면 TLB에 엔트리를 리필하고, 비상주 시 OS 페이지 폴트 예외 발생

#### 한줄 요약

- 적중 시 **1클록 주소 변환**, 미스 시 **하드웨어 페이지 순회 및 페이지 폴트 트랩**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLB Miss vs Page Fault**:
  - TLB Miss: 하드웨어 워커가 해결 (수십~수백 사이클)
  - Page Fault: OS 커널이 디스크 I/O로 해결 (수백만 사이클)

</details>

| 비교 항목 | TLB 미스 (TLB Miss) | 페이지 폴트 (Page Fault) |
|:---|:---|:---|
| 발생 원인 | 최근 주소 변환 매핑이 TLB 캐시에 부재 | 가상 페이지가 물리 메모리(DRAM)에 부재(비상주) |
| 처리 주체 | MMU 내 하드웨어 페이지 워커 (HW Page Walker) | 운영체제(OS) 커널 소프트웨어 예외 핸들러 |
| 소요 지연 | 수십~수백 사이클 (DRAM 페이지 테이블 순회) | 수백만 사이클 (디스크 I/O 스왑 인, 메이저 폴트) |
| 해결 방법 | 페이지 테이블 탐색 후 TLB 엔트리 리필 | 디스크에서 물리 프레임으로 적재 후 PTE/TLB 갱신 |

#### 한줄 요약

- TLB 미스는 **하드웨어 순회 지연**, 페이지 폴트는 **OS 디스크 스왑 입출력 지연**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대형 페이지(Huge Page / Superpage)**: 기본 4KB 대신 2MB, 1GB 단위 페이지를 사용하여 동일 TLB 엔트리 수로 수천 배의 메모리 영역을 커버하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 데이터 작업 집합이 **TLB 도달 범위**를 초과 | 운영체제 환경 설정으로 **대형 페이지** 적용 | 극단적인 변환 미스 감소 및 주소 도달 범위 기하급수적 확대 |
| 프로세스 문맥 전환 시 전체 캐시 내용 폐기 발생 | 식별자 태그 유지 및 **선택적 무효화** 명령어 적용 | 전환 직후 초기화 미스 극소화 및 파이프라인 유지 |
| 다단계 테이블의 반복되는 메모리 접근 지연 병목 | 하드웨어 내부 **페이지 순회 캐시** 탑재로 상위 항목 보존 | 실제 메모리 접근 횟수 차단 및 순회 지연 단축 |
| 대형 페이지 설정 시 물리 공간 분할로 인한 내부 단편화 | 운영체제 주기적 메모리 병합 구동 및 전용 구역 파티셔닝 | 단편화 부작용 차단 및 거대 페이지의 긍정적 혜택 보존 |

#### 한줄 요약

- **대형 페이지(Huge Page)·ASID 태그·Page Walk Cache**로 변환 지연 극소화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **2단계 가상화 TLB(Nested/Shadow TLB)**: 하이퍼바이저 가상화 환경에서 Guest VA $\to$ Guest PA $\to$ Host PA 2단계 변환 오버헤드를 완화하는 하드웨어 가속 확장(EPT/NPT).

</details>

- 대규모 워크로드(DBMS/AI) 환경에서 **대형 페이지(2MB/1GB) 적용 및 ASID 기반 문맥 전환 최적화**

#### 한줄 요약

- **작업 집합 크기와 문맥 전환 빈도**에 맞춘 TLB 도달 범위 및 엔트리 최적화
