## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 가상 페이지와 물리 프레임의 변환 결과를 저장하는 주소 변환 캐시입니다.
- **메모리 관리 장치(Memory Management Unit, MMU)**: 주소 변환과 메모리 접근 권한을 검사하는 하드웨어입니다.
- **페이지 테이블(Page Table)**: 가상 페이지와 물리 프레임의 대응 정보를 저장하는 메모리 구조입니다.

</details>

- 정의/개념: 페이지 테이블 순회를 줄이는 **가상·물리 주소 변환 캐시**
- 배경/필요성: 반복 주소 접근에서 변환 지연과 메모리 참조 증가 완화

#### 한줄 요약

- TLB는 자주 쓰는 주소 번역 결과를 가까이 보관해 매번 페이지 테이블을 처음부터 찾지 않게 하는 장치입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리가 어느 프로세스 주소 공간에 속하는지 구분하는 식별자입니다.
- **TLB 도달 범위(TLB Reach)**: TLB 엔트리 수와 페이지 크기를 곱해 얻는 변환 커버리지입니다.
- **대형 페이지(Huge Page)**: 기본 페이지보다 큰 단위로 주소 공간을 매핑해 한 엔트리의 커버리지를 넓히는 방식입니다.

</details>

- 최근 변환 재사용에 따른 **페이지 테이블 순회 감소**
- ASID 태깅에 따른 **문맥 전환 비용 완화**
- 대형 페이지에 따른 **TLB 도달 범위 확대**

#### 한줄 요약

- 프로세스가 같은 영역을 반복해서 쓰면 변환 결과를 재사용할 수 있고, ASID와 대형 페이지는 각각 전환과 커버리지 문제를 줄여 줍니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 페이지 번호(Virtual Page Number, VPN)**: 가상 주소에서 페이지를 식별하는 상위 주소 부분입니다.
- **물리 프레임 번호(Physical Page Number, PPN)**: 변환 결과인 물리 메모리 프레임을 식별하는 번호입니다.
- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 때 페이지 테이블을 순회해 변환을 찾는 하드웨어 또는 제어 기능입니다.

</details>

```text
[주소 변환 경로]
├─ TLB 조회기
├─ TLB 엔트리
│  ├─ VPN·PPN
│  ├─ ASID
│  └─ 권한·유효 상태
├─ 페이지 테이블 워커
└─ 페이지 테이블
```

| 구성요소 | 책임 |
|:---|:---|
| TLB 조회기 | VPN·ASID와 엔트리 비교 |
| TLB 엔트리 | VPN·PPN과 권한 상태 저장 |
| 페이지 테이블 워커 | 미스 때 페이지 테이블 순회 |
| 페이지 테이블 | 가상 페이지·물리 프레임 매핑 보관 |

#### 한줄 요약

- TLB는 빠른 비교를 맡고, 워커와 페이지 테이블은 TLB에 없는 변환을 찾아 다시 TLB에 채우는 역할을 맡습니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: 요청한 가상 페이지의 변환이 TLB에 있어 즉시 물리 주소를 만들 수 있는 상태입니다.
- **TLB 미스(TLB Miss)**: 변환이 TLB에 없어 페이지 테이블 확인이 필요한 상태입니다.
- **페이지 폴트(Page Fault)**: 페이지 부재 또는 권한 문제로 운영체제 예외 처리가 필요한 상황입니다.

</details>

```text
[1. VPN·ASID 조회]
          │
          ├─ 적중 → [2. PPN·오프셋 결합]
          │
          └─ 미스 → [2. 페이지 테이블 순회]
                         │
                         ├─ 유효 → [3. TLB 리필·주소 생성]
                         └─ 부재·권한 오류 → [3. 페이지 폴트]
```

동작 원리:

1. VPN·ASID 조회: 요청 주소와 주소 공간 식별자를 TLB와 비교
2. PPN·오프셋 결합 또는 페이지 테이블 순회: 적중·미스별 변환 수행
3. TLB 리필·주소 생성 또는 페이지 폴트: 유효 매핑 반영 또는 OS 예외 전달

#### 한줄 요약

- TLB에 번역이 있으면 곧바로 물리 주소를 만들고, 없으면 표를 다시 찾으며 표에도 답이 없거나 권한이 없을 때 운영체제로 넘깁니다.

## Ⅴ. 종류 및 비교

| 주소 변환 실패 | TLB 미스 | 페이지 폴트 |
|:---|:---|:---|
| 적용 기준 | 변환은 존재하지만 TLB에 없음 | 페이지 부재 또는 접근 권한 오류 |
| 핵심 특징 | 워커 또는 OS가 페이지 테이블 확인 | OS 예외 처리와 페이지 상태 변경 |
| 한계 | 테이블 깊이만큼 메모리 지연 증가 | 저장장치 접근 시 매우 큰 지연 |

#### 한줄 요약

- TLB 미스는 번역표를 다시 찾는 문제이고, 페이지 폴트는 번역표의 상태나 권한을 운영체제가 해결해야 하는 문제입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페이지 워크 캐시(Page Walk Cache)**: 페이지 테이블 상위 항목을 저장해 반복 순회의 메모리 접근을 줄이는 캐시입니다.
- **선택적 무효화(Selective Invalidation)**: 주소 공간 또는 특정 엔트리만 골라 TLB에서 제거하는 처리입니다.
- **내부 단편화(Internal Fragmentation)**: 큰 페이지를 사용하면서 실제 데이터보다 많은 공간을 할당해 낭비하는 현상입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 집합이 TLB 도달 범위를 초과 | 대형 페이지와 페이지 배치 조정 | 변환 미스와 워크 횟수 감소 |
| 문맥 전환마다 전체 TLB 폐기 | ASID와 선택적 무효화 적용 | 전환 직후 미스 증가 완화 |
| 다단계 순회가 반복되어 메모리 지연 발생 | 페이지 워크 캐시 적용 | 순회 메모리 접근과 지연 감소 |
| 대형 페이지가 내부 단편화 유발 | 큰 연속 영역에만 선택 적용 | 커버리지 이득과 공간 낭비 균형 |

#### 한줄 요약

- TLB 용량만 키우기보다 작업 집합 크기와 문맥 전환, 페이지 크기를 함께 조정해야 변환 비용을 줄일 수 있습니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **작업 집합(Working Set)**: 일정 시간 동안 프로그램이 실제로 반복 접근하는 메모리 페이지의 집합입니다.

</details>

- **작업 집합**이 TLB 도달 범위를 자주 넘으면 대형 페이지·ASID를 적용하고, 단편화·보호·할당 제약이 크면 기본 페이지를 유지하는 방향으로 결정

#### 한줄 요약

- TLB 최적화는 엔트리 수만 늘리는 일이 아니라 프로그램이 실제로 사용하는 페이지 범위와 운영체제의 페이지 관리 비용을 함께 맞추는 일입니다.
