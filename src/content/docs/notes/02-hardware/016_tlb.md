## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer)**: 가상 주소를 물리 주소로 변환 시 다단계 페이지 테이블 탐색 과정을 우회하도록 최근 매핑 주소를 초고속 저장하는 캐시이다.
- **메모리 관리 장치(Memory Management Unit)**: 주소 변환, 캐시 제어 및 접근 권한 검사를 총괄 구동하는 하드웨어 블록이다.
- **다단계 페이지 순회(Multi-Level Page Walk)**: 64비트 환경에서 테이블 엔트리를 찾기 위해 주기억장치를 연속 재귀 접근하는 작업이다.

</details>

- 정의: 가상 주소를 물리 주소로 변환할 때 최근 매핑 정보를 고속 보관하는 **메모리 관리 장치** 내부의 **변환 색인 버퍼**
- 배경: 주소 변환 시 발생하는 **다단계 페이지 순회**로 인한 극심한 메모리 지연 병목을 해결하기 위함

#### 한줄 요약

- 주소 변환 결과를 고속 캐싱하여 다단계 페이지 테이블 접근에 따른 메모리 지연을 획기적으로 줄이는 하드웨어 장치이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier)**: 프로세스별로 고유 할당되어 문맥 전환 발생 시에도 변환 엔트리를 식별하는 태그이다.
- **TLB 도달 범위(TLB Reach)**: 변환 색인 버퍼의 엔트리 수와 페이지 크기의 곱으로 계산되는 주소 변환 커버리지 용량이다.
- **작업 집합(Working Set)**: 프로그램이 특정 시간 동안 집중적으로 반복 접근하는 메모리 페이지들의 묶음이다.
- **TLB 엔트리 수(TLB Entry Count)**: 하드웨어 내부에 물리적으로 적재 가능한 가상 및 물리 매핑 쌍의 개수이다.
- **접근 권한(Access Permission)**: 페이지별 읽기, 쓰기, 실행 및 커널 모드 권한을 제어하는 보안 제어 비트이다.

</details>

- 최근 주소 변환 결과를 **주소 공간 식별자**와 병렬 대조하여 극히 짧은 지연으로 물리 주소를 반환함.
- 프로세스 전환 시 식별자 태그를 통해 전체 캐시 비우기를 우회하여 오버헤드를 극소화함.
- **TLB 도달 범위**가 프로그램의 **작업 집합** 크기보다 작을 경우 미스가 다발하여 성능 저하가 발생함.

#### 한줄 요약

- 식별자를 통한 무중단 문맥 전환을 지원하며 도달 범위를 기반으로 주소 변환 지연시간을 은닉한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 페이지 번호(Virtual Page Number)**: 가상 주소의 상위 비트로 탐색 시 태그 매칭에 사용되는 인덱스 번호이다.
- **물리 페이지 번호(Physical Page Number)**: 적중 시 변환 출력되는 실제 주기억장치의 고유 프레임 번호이다.
- **TLB 엔트리(TLB Entry)**: 가상 및 물리 번호, 식별자, 상태 및 권한 비트로 묶인 하나의 매핑 행이다.
- **페이지 테이블 순회기(Page Table Walker)**: 미스 발생 시 하드웨어적으로 다단계 페이지 테이블을 따라 메모리를 연속 접근하는 장치이다.
- **TLB 조회기(TLB Lookup Unit)**: 전체 태그와 입력 번호를 단일 주기에 병렬 대조하는 회로 블록이다.

</details>

```text
[ 가상 주소 : 가상 페이지 번호 + 페이지 오프셋 ]
                        │
                        ▼
            [ TLB 조회기 병렬 탐색 ]
            ├─ 적중 시 ──> 물리 페이지 번호 인출
            │
            └─ 미스 시 ──> [ 페이지 테이블 순회기 구동 ]
                                  │
                                  ▼
                           [ 캐시 채우기 및 번호 반환 ]
```

| 구성요소 | 책임 |
|:---|:---|
| TLB 조회기 | **가상 페이지 번호**와 **주소 공간 식별자** 및 **접근 권한** 병렬 비교 |
| TLB 엔트리 배열 | 가상 및 물리 번호 매핑쌍과 상태 비트 저장 보존 |
| 페이지 테이블 순회기 | 미스 발생 시 다단계 테이블 탐색 및 캐시 채우기 자동 수행 |

#### 한줄 요약

- 조회기가 병렬 탐색을 수행하고, 미스 시 하드웨어 순회기가 메모리 접근을 통해 배열 엔트리를 채운다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: 입력 번호에 해당하는 매핑이 유효하게 존재하여 즉시 물리 번호를 반환하는 상태이다.
- **TLB 미스(TLB Miss)**: 매핑이 없어 순회기가 메인 메모리의 페이지 테이블을 탐색해야 하는 상태이다.
- **페이지 오프셋(Page Offset)**: 페이지 내의 상대 위치를 지정하며 주소 변환 시 하위 비트로 그대로 복사되는 값이다.
- **페이지 폴트(Page Fault)**: 해당 페이지가 물리 메모리에 존재하지 않을 때 발생하는 운영체제 예외 트랩이다.

</details>

```text
[ 가상 주소 접근 요청 발생 ]
          │
          ▼
    [ TLB 병렬 조회 ]
          │
    ├─ 적중 ──> [ 페이지 오프셋 결합 및 물리 주소 반환 ]
    │
    └─ 미스 ──> [ 하위 다단계 페이지 테이블 탐색 ]
                        │
                        ├─ 조건 충족 ──> [ 캐시 갱신 및 반환 ]
                        │
                        └─ 예외 상황 ──> [ 페이지 폴트 예외 트랩 구동 ]
```

### 동작 원리

1. 조회: 가상 주소의 **가상 페이지 번호**와 식별자를 엔트리와 병렬 비교함.
2. 적중 처리: **TLB 적중** 시 **물리 페이지 번호**와 **페이지 오프셋**을 결합하고 권한을 검사함.
3. 미스 처리: **TLB 미스** 시 **페이지 테이블 순회기**가 다단계 메모리 테이블을 탐색함.
4. 채우기 및 예외: 엔트리가 유효하면 캐시를 채우고, 비상주 시 **페이지 폴트** 예외를 발생시킴.

#### 한줄 요약

- 적중 시 지연 없이 물리 주소를 결합하며, 미스 시 하드웨어 탐색 후 채우거나 운영체제 예외 트랩을 가동한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 순회 지연(Page Walk Latency)**: 변환 미스 시 주기억장치 테이블을 연속으로 읽으면서 소비되는 수십 사이클의 지연시간이다.

</details>

| 비교 항목 | TLB 미스 | 페이지 폴트 |
|:---|:---|:---|
| 처리 주체 | **하드웨어** 페이지 테이블 순회기 | **소프트웨어** 운영체제 예외 처리기 |
| 발생 원인 | 최근 변환 매핑이 고속 캐시에 없음 | 메모리 비상주나 권한 위반 등 예외 조건 |
| 소요 지연 | **페이지 순회 지연** 발생 | 디스크 입출력으로 인한 막대한 지연 발생 |
| 해결 방법 | 테이블 탐색 후 캐시 채우기 수행 | 운영체제가 원인을 판정하여 메모리 적재 처리 |
| 시스템 영향 | 주소 변환 파이프라인 일시 정지 | 스레드 스케줄링 대기 또는 예외 강제 종료 |

#### 한줄 요약

- 변환 캐시 부재는 하드웨어 탐색 지연을 유발하며, 물리 메모리 부재는 운영체제 개입과 입출력 지연을 유발한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대형 페이지(Huge Page)**: 표준 4KB 단위 대신 수십 MB 및 GB 단위의 거대 페이지를 적용하여 변환 커버리지를 확장하는 기법이다.
- **페이지 순회 캐시(Page Walk Cache)**: 다단계 페이지 테이블의 상위 래디스 엔트리 주소만을 따로 캐싱하여 접근 횟수를 줄이는 전용 버퍼이다.
- **선택적 무효화(Selective Invalidation)**: 전환 시 전체를 비우지 않고 특정 가상 주소 페이지 엔트리만 지정하여 지우는 최적화 명령이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 데이터 작업 집합이 **TLB 도달 범위**를 초과 | 운영체제 환경 설정으로 **대형 페이지** 적용 | 극단적인 변환 미스 감소 및 주소 도달 범위 기하급수적 확대 |
| 프로세스 문맥 전환 시 전체 캐시 내용 폐기 발생 | 식별자 태그 유지 및 **선택적 무효화** 명령어 적용 | 전환 직후 초기화 미스 극소화 및 파이프라인 유지 |
| 다단계 테이블의 반복되는 메모리 접근 지연 병목 | 하드웨어 내부 **페이지 순회 캐시** 탑재로 상위 항목 보존 | 실제 메모리 접근 횟수 차단 및 순회 지연 단축 |
| 대형 페이지 설정 시 물리 공간 분할로 인한 내부 단편화 | 운영체제 주기적 메모리 병합 구동 및 전용 구역 파티셔닝 | 단편화 부작용 차단 및 거대 페이지의 긍정적 혜택 보존 |

#### 한줄 요약

- 대형 페이지를 통한 커버리지 확장과 식별자 기반 유지보수, 전용 순회 캐시 탑재로 탐색 병목과 단편화를 모두 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **TLB 최적화 기준(TLB Optimization Criteria)**: 워크로드의 작업 집합 규모, 문맥 전환 빈도, 다단계 깊이를 종합하여 대형 페이지 및 식별자 적용을 결정하는 기준이다.

</details>

- 작업 집합이 도달 범위를 초과하면 **대형 페이지**, 전환이 잦으면 식별자 태그를 적용함

#### 한줄 요약

- 작업 특성에 따른 변환 미스 원인과 메모리 단편화 비용을 종합적으로 측정하여 최적의 페이지 크기와 유지 정책을 결정해야 한다.
