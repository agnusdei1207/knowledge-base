## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 내부에 위치하여 가상 주소의 물리 주소 변환, 메모리 보호 및 접근 권한 검증을 하드웨어적으로 전담하는 핵심 장치.
- **변환 참조 버퍼(Translation Lookaside Buffer, TLB)**: CPU 내부 MMU에 탑재되어 최근 사용된 페이지 매핑(VPN-PPN)을 저장함으로써 다단계 페이지 테이블 순회를 생략시키는 고속 주소 변환 캐시.
- **내용 주소화 기억장치(Content Addressable Memory, CAM)**: TLB 하드웨어 내부에 내장되어, 입력된 가상 페이지 번호(VPN)를 전체 엔트리와 단 1클록 만에 동시 병렬 비교하는 고속 연관 검색 회로.
- **가상 페이지 번호(Virtual Page Number, VPN)**: 프로세스 가상 주소(VA)에서 오프셋을 제외한 상위 비트 필드로, TLB의 CAM 태그 비교 및 페이지 테이블 탐색의 기준이 되는 식별자.
- **물리 페이지 번호(Physical Page Number, PPN)**: 주소 변환 결과로 도출되어 오프셋과 결합하는 실제 메인 메모리(DRAM)의 프레임 기준 번호(Page Frame Number, PFN).

</details>

- 정의/개념: CPU 내부 **메모리 관리 장치(MMU)**에 위치하여 **가상 페이지 번호(VPN)**와 **물리 페이지 번호(PPN)** 매핑을 고속 캐싱하는 주소 변환 하드웨어 캐시
- 배경/필요성: 가상 메모리 주소 변환 시 DRAM 상의 **다단계 페이지 테이블 순회(Page Walk)**에 따른 중복 메모리 접근 지연 병목 해소

#### 한줄 요약
- TLB는 CPU 내부 MMU에 위치하는 주소 변환 전용 캐시로, 데이터 캐시와 달리 미스 발생 시 다단계 메모리 순회가 수반되므로 성능 영향이 매우 크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리에 각 프로세스 고유 식별자를 태깅하여, 문맥 전환(Context Switch) 시 TLB 전체 플러시 없이 복수 프로세스 엔트리의 공존을 보장하는 태그.
- **TLB 도달 범위(TLB Reach)**: TLB 전체 엔트리 수와 페이지 크기의 곱($TLB\,Entries \times Page\,Size$)으로 결정되는, TLB가 미스 없이 직접 매핑할 수 있는 총 가상 메모리 용량.
- **대형 페이지(Huge Page)**: 표준 4KB 페이지 대신 2MB, 1GB 등 대용량 페이지 단위를 적용하여 동일한 TLB 엔트리 수로 TLB 도달 범위를 획기적으로 확장하는 기법.

</details>

- CPU ➔ MMU ➔ TLB 하드웨어 계층 캐싱을 통한 **다단계 페이지 테이블 순회** 생략 및 1클록 내 주소 변환 완료
- 엔트리별 **ASID** 태깅을 통한 문맥 전환 시 TLB 플러시 오버헤드 제거 및 다중 프로세스 매핑 공존
- **대형 페이지** 적용으로 제한된 TLB 엔트리 수 대비 직접 커버 가능한 **TLB 도달 범위** 확장

#### 한줄 요약
- TLB 도달 범위는 엔트리 수와 페이지 크기의 곱으로 결정되며, 회로 면적 한계상 엔트리를 늘리기보다 대형 페이지를 적용하는 것이 유리하다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 중지하고 메모리 상의 다단계(Multi-level) 페이지 테이블을 계층적으로 순회(Page Walk)하여 변환 정보를 인출하는 MMU 내부 하드웨어 유닛.
- **SRAM 엔트리 배열**: CAM 회로의 병렬 태그 비교 적중 신호에 따라 대응하는 물리 페이지 번호(PPN)와 제어 비트를 즉시 출력하는 저장 셀 배열.

</details>

```text
[CPU 코어 (Core)]
 └─ [메모리 관리 장치 (MMU)]
     ├─ [변환 참조 버퍼 (TLB)]
     │   ├─ CAM 고속 비교 회로 (VPN·ASID 전 엔트리 1클록 병렬 비교)
     │   └─ SRAM 엔트리 배열 (PPN / 접근 권한 / 유효·더티 비트 보관)
     └─ [페이지 테이블 워커 (Page Table Walker)]
         │ (TLB 미스 시 주소 버스 접근)
         ▼
[메인 메모리 (DRAM)]
 └─ 다단계 페이지 테이블 (Page Table: OS 커널 관리 주소 매핑 정본)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 화살표(`▼`)는 TLB 미스 시 하드웨어 워커의 DRAM 계층 순회 경로

| 구성요소 | 계층 및 소속 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **MMU** | CPU 내부 핵심 장치 | 가상 주소의 물리 주소 변환 및 메모리 접근 보호 권한 하드웨어 검증 | 주소 변환 및 접근 제어 총괄 |
| **TLB** | MMU 내부 고속 캐시 | 최근 사용된 VPN-PPN 매핑을 보관하여 Page Walk를 생략하는 **MMU 내부 주소 캐시** | 1클록 주소 변환 제공 |
| **CAM 회로** | TLB 내부 검색 엔진 | 입력된 VPN·**ASID**를 전 엔트리와 동시 대조하는 **내용 주소화 기억장치** 회로 | 전연관 1클록 병렬 비교 |
| **SRAM 엔트리** | TLB 내부 저장 배열 | VPN 매핑 PPN, ASID, 권한(R/W/X), 유효(V), 변경(D) 비트 보관 | 변환 정보 고속 인출 |
| **페이지 테이블 워커** | MMU 내부 제어 유닛 | TLB 미스 발생 시 DRAM 상의 **다단계 페이지 테이블을 하드웨어로 계층 순회** | 하드웨어 기반 변환 복구 |
| **페이지 테이블** | 메인 메모리(DRAM) 상주 | OS 커널이 관리하는 **가상 주소 공간과 물리 메모리 프레임 간 전체 매핑 정본** | 다단계 트리형 소프트웨어 정본 |

#### 한줄 요약
- CPU 내 MMU가 TLB(CAM+SRAM)와 하드웨어 워커를 내장함으로써, 1클록 고속 주소 변환과 미스 시 자동 계층 순회를 모두 하드웨어 레벨에서 완결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: CPU가 요청한 가상 페이지 번호(VPN)가 MMU 내 TLB(CAM)에서 1클록 만에 일치하여 메모리 접근 없이 물리 주소를 도출하는 상태.
- **TLB 미스(TLB Miss)**: 요청된 VPN이 TLB에 존재하지 않아 MMU의 하드웨어 페이지 테이블 워커가 DRAM 상의 페이지 테이블 순회를 개시하는 지연 상태.
- **페이지 폴트(Page Fault)**: 페이지 테이블 순회 결과 물리 메모리에 대상 페이지가 부재(Present=0)하거나 권한을 위반하여 OS 커널 트랩 핸들러로 제어가 전환되는 예외.

</details>

```text
CPU 가상 주소(VA) 발생
       │
       ▼
1. MMU 내 TLB(CAM) 병렬 태그 비교
       │
       ├─ 적중 (TLB Hit) ──► PPN·오프셋 결합 ──► 물리 주소 생성 (1클록 완료)
       │
       └─ 미스 (TLB Miss)
              │
              ▼
       2. 하드웨어 워커의 DRAM 다단계 페이지 테이블 순회 (Page Walk)
              │
              ├─ 매핑 유효 (Present=1) ──► TLB(CAM/SRAM) 리필 ──► 물리 주소 생성
              │
              └─ 부재·권한 위반 ──► 3. 페이지 폴트 인터럽트 발생 ──► OS 커널 핸들러 처리
```

분기 결과: **TLB 적중은** 1클록 단위로 완결되고 **TLB 미스는** 메모리 버스 접근 단위로 지연되지만, **페이지 폴트**는 디스크 스왑 입출력이 수반되어 처리 지연이 자릿수 단위로 급증함

#### 한줄 요약
- 세 경로는 동일한 단일 메모리 참조에서 분기하지만, 하드웨어 1클록 캐시 적중에서부터 소프트웨어 디스크 I/O 트랩까지 지연시간이 자릿수 단위로 격차를 보인다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLB 미스(TLB Miss)**: 하드웨어 워커가 페이지 테이블을 순회하여 TLB를 리필하는 MMU 하드웨어 레벨 지연 사건.
- **페이지 폴트(Page Fault)**: 대상 페이지가 DRAM에 없어 OS가 보조기억장치에서 페이지를 반입하는 운영체제 커널 레벨 예외 사건.

</details>

| 주소 변환 사건 | TLB 미스 (TLB Miss) | 페이지 폴트 (Page Fault) |
|:---|:---|:---|
| 적용 기준 | **유효 매핑은 DRAM에 존재하나 TLB에 캐싱되지 않음** | **물리 메모리 페이지 부재(Present=0) 또는 접근 권한 위반** |
| 핵심 특징 | **MMU 하드웨어 워커가 순회 후 TLB CAM 리필 및 파이프라인 재개** | **OS 커널 인터럽트로 스왑 영역 반입 및 페이지 테이블 갱신 후 재시도** |
| 한계 | 다단계 페이지 테이블 깊이(4~5단계)만큼 DRAM 접근 지연 (수십 ns)| 디스크/스토리지 I/O 접근으로 인한 초장시간 파이프라인 중단 (수 ms) |
| 처리 주체 및 소속 | **하드웨어 (CPU 내부 MMU Page Table Walker)** | **소프트웨어 커널 (OS Page Fault Handler)** |

#### 한줄 요약
- TLB 미스는 CPU 내부 MMU 하드웨어가 자체 해결하는 지연 사건이고, 페이지 폴트는 OS 커널이 스토리지 I/O로 해결하는 시스템 예외 사건이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페이지 워크 캐시(Page Walk Cache)**: MMU 내부에 위치하여 다단계 페이지 테이블 순회 시 상위 디렉터리(PML4, PDP 등) 변환 결과를 별도 캐싱하는 하드웨어 캐시.
- **선택적 무효화(Selective Invalidation)**: 프로세스 종료나 메모리 해제 시 전체 TLB를 플러시하지 않고 특정 가상 주소나 ASID 엔트리만 선별 무효화하는 명령어(INVLPG, TLBI 등).
- **내부 단편화(Internal Fragmentation)**: 대형 페이지 할당 시 실제 프로세스가 요구하는 메모리보다 큰 고정 블록이 할당되어 페이지 내부 공간이 낭비되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 워크로드 실행 시 **TLB 도달 범위** 초과로 변환 미스 급증 | **대형 페이지(Huge Page: 2MB/1GB)** 적용 및 연속 메모리 할당 | TLB 엔트리당 커버 용량 증대로 Page Walk 발생 빈도 대폭 감소 |
| 문맥 전환마다 전체 TLB 플러시로 인한 파이프라인 콜드 미스 발생 | **ASID 태깅** 및 **선택적 무효화(INVLPG)** 명령어 적용 | 프로세스 전환 후에도 기존 엔트리 유지로 초기 주소 변환 지연 완화 |
| 4~5단계 다단계 순회 반복으로 메모리 버스 지연 오버헤드 누적 | **페이지 워크 캐시(Page Walk Cache)** 하드웨어 활성화 | 상위 디렉터리 재순회 생략 및 워크 지연 단축 |
| 대형 페이지 도입 시 프로세스 메모리의 **내부 단편화** 발생 | 대규모 연속 메모리(DB 버퍼 풀 등)에만 **선택적 대형 페이지 적용** | TLB 적중률 향상과 DRAM 낭비의 균형 달성 |

#### 한줄 요약
- TLB는 CAM 병렬 회로 특성상 용량을 무한정 늘릴 수 없으므로, 대형 페이지와 ASID 및 페이지 워크 캐시를 결합하여 실무 성능 한계를 극복한다.

## Ⅶ. 결론

- CPU 내부 **MMU에 탑재된 CAM 기반 TLB 하드웨어 캐싱으로 1클록 주소 변환을 보장**하고, 대규모 워크로드 환경에서는 **대형 페이지(Huge Page)와 ASID 태깅 및 페이지 워크 캐시**를 유기적으로 결합하여 주소 변환 지연을 극소화하는 메모리 가상화 아키텍처 확립

#### 한줄 요약
- TLB는 CPU ➔ MMU ➔ CAM 하드웨어 계층 구조를 통해 1클록 주소 변환을 달성하며, 대형 페이지와 ASID를 결합하여 가상 메모리 시스템의 성능 병목을 해소한다.
