## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 참조된 가상 페이지 번호(VPN)와 물리 프레임 번호(PPN)의 주소 변환 매핑을 캐싱하여 페이지 테이블 순회 오버헤드를 줄이는 고속 완전/집합 연관 CAM 캐시.
- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU가 발생시킨 가상 주소를 물리 주소로 실시간 변환하고 메모리 접근 권한 및 보호 속성을 하드웨어적으로 검사하는 제어 장치.
- **페이지 테이블(Page Table)**: 가상 주소 공간의 각 페이지에 대응하는 물리 메모리 프레임 번호, 접근 제어 비트(R/W/X), 존재 비트(Present/Valid) 등을 저장하는 메모리 상의 매핑 자료구조.
- **가상 페이지 번호(Virtual Page Number, VPN)**: 가상 주소(VA)에서 페이지 오프셋을 제외한 상위 비트 필드로, 페이지 테이블 검색 및 TLB 태그 비교의 기준이 되는 식별자.
- **물리 페이지 번호(Physical Page Number, PPN)**: 주소 변환 결과로 도출되는 실제 물리 메모리(DRAM)의 프레임 기준 번호(Page Frame Number, PFN).

</details>

- 정의/개념: **가상 페이지 번호(VPN)** 및 **물리 페이지 번호(PPN)** 대응을 캐싱해 재순회를 없애는 **메모리 관리 장치(MMU)** 내부 캐시
- 배경/필요성: 다단계 **페이지 테이블** 순회는 데이터 한 번 읽는 데 메모리 접근을 여러 번 더 요구해 변환 자체가 병목이 됨

#### 한줄 요약
- **TLB는** 데이터 캐시와 달리 미스 한 번에 메모리 접근이 여러 번 따라붙으므로, 같은 미스율이라도 성능에 미치는 타격이 훨씬 크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리에 각 프로세스의 고유 프로세스 ID를 태깅하여, 문맥 전환(Context Switch) 시 TLB 전체 플러시 없이 복수 프로세스의 엔트리가 공존하도록 하는 식별자.
- **TLB 도달 범위(TLB Reach)**: TLB 전체 엔트리 수와 각 엔트리가 매핑하는 페이지 크기의 곱($TLB\,Entries \times Page\,Size$)으로 계산되는, TLB가 메모리 접근 시 미스 없이 직접 커버할 수 있는 총 가상 메모리 용량.
- **대형 페이지(Huge Page)**: 표준 4KB 페이지 대신 2MB, 1GB 등 대용량 페이지 단위를 사용하여 동일한 TLB 엔트리 수로 TLB 도달 범위를 획기적으로 확장하는 기법.

</details>

- 최근 변환을 재사용해 페이지 테이블 순회 횟수를 줄이고 주소 변환 지연 단축
- **ASID** 태깅으로 문맥 전환 시 TLB 플러시 없이 다수 프로세스 엔트리 공존
- **대형 페이지** 적용으로 단일 엔트리가 커버하는 **TLB 도달 범위** 확대

#### 한줄 요약
- **TLB 도달 범위는** 엔트리 수와 페이지 크기의 곱이라는 점이 핵심이며, 엔트리를 늘리는 것보다 페이지를 키우는 쪽이 훨씬 싸게 같은 효과를 낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 중지하고 메모리 상의 다단계(Multi-level) 페이지 테이블을 계층적으로 순회(Page Walk)하여 변환 정보를 인출하는 하드웨어 유닛.

</details>

```text
[MMU 주소 변환 구조]
├─ TLB 조회기
│  └─ TLB 엔트리 (VPN·ASID / PPN / 권한·유효 비트)
└─ 페이지 테이블 워커
   └─ 페이지 테이블 (메모리 내)
```

선의 의미: 가지(`├─`)는 소유·연결 관계; 페이지 테이블 워커와 페이지 테이블은 TLB 미스 경로에서만 활성화

| 구성요소 | 책임 |
|:---|:---|
| TLB 조회기 | VPN·**ASID**를 엔트리와 병렬 비교해 적중 판정 |
| TLB 엔트리 | VPN·PPN·권한·유효 비트 저장 |
| **페이지 테이블 워커** | 변환이 없을 때 다단계 페이지 테이블 순회 |
| 페이지 테이블 | 가상 페이지·물리 프레임 전체 매핑 보관 |

#### 한줄 요약
- 워커가 하드웨어에 들어온 덕분에 미스가 예외가 아니라 지연으로 바뀌었고, 그 결과 변환 실패는 OS 문제에서 성능 문제로 성격이 바뀌었다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: CPU가 요청한 가상 페이지 번호(VPN)와 ASID가 TLB 내에 유효하게 존재하여 추가 메모리 접근 없이 단일 클록 내에 물리 주소(PPN)를 생성하는 상태.
- **TLB 미스(TLB Miss)**: 요청된 VPN의 변환 엔트리가 TLB에 존재하지 않아 하드웨어 페이지 테이블 워커가 메모리의 페이지 테이블을 순회해야 하는 상태.
- **페이지 폴트(Page Fault)**: 주소 변환 과정에서 요청된 페이지가 물리 메모리에 상주하지 않거나(Present=0), 접근 권한(R/W/X)을 위반하여 OS 커널의 예외 처리 루틴으로 제어가 전환되는 하드웨어 인터럽트.

</details>

```text
가상 주소 입력
      │
      ▼
1. VPN 및 ASID TLB 조회
      │
      ├─ 적중 → PPN·오프셋 결합 → 물리 주소 생성
      │
      └─ 미스
             │
             ▼
      2. TLB 미스 시 페이지 테이블 워커 순회
             │
             ├─ 유효 매핑 → TLB 리필 → 물리 주소 생성
             │
             └─ 부재·권한 오류 → 3. 페이지 폴트 및 예외 처리 → OS 처리
```

분기 결과: **TLB 적중은** 클록 단위로 끝나고 **TLB 미스는** 메모리 접근 단위로 끝나지만, **페이지 폴트**만은 저장장치 단위라 세 경로의 비용 차이가 자릿수 단위로 벌어짐

#### 한줄 요약
- 세 경로가 모두 같은 한 번의 메모리 참조에서 갈리기 때문에, 프로그램 입장에서는 예측할 수 없는 지연 편차로 나타난다.

## Ⅴ. 종류 및 비교

| 주소 변환 사건 | TLB 미스 | 페이지 폴트 |
|:---|:---|:---|
| 적용 기준 | 유효 매핑은 있으나 TLB에 캐싱되지 않음 | 페이지 부재 또는 접근 권한 오류 |
| 핵심 특징 | 워커가 순회 후 TLB를 다시 채우고 재개 | OS 예외 처리로 적재·권한 변경 후 재시도 |
| 한계 | 페이지 테이블 깊이만큼 메모리 접근 지연 | 저장장치 접근 시 매우 큰 지연 |

#### 한줄 요약
- 둘은 같은 미스처럼 보이지만 처리 주체가 하드웨어와 소프트웨어로 갈리며, 그 경계가 곧 성능 문제와 정합성 문제의 경계가 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페이지 워크 캐시(Page Walk Cache)**: 다단계 페이지 테이블 순회 시 상위 단계(PML4, PDP, PD 등) 디렉터리 엔트리의 주소 변환 결과를 별도로 캐싱하여 순회 지연시간을 단축하는 특수 캐시.
- **선택적 무효화(Selective Invalidation)**: 특정 프로세스의 종료나 메모리 해제(munmap) 시 전체 TLB를 비우지 않고 해당 가상 주소 범위 또는 ASID에 해당하는 특정 엔트리만 선별하여 무효화하는 명령어(INVLPG, TLBI 등).
- **내부 단편화(Internal Fragmentation)**: 대형 페이지 할당 시 실제 프로세스가 필요로 하는 메모리보다 큰 고정 블록이 할당되어 페이지 내부에서 사용되지 않고 낭비되는 메모리 공간.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작업 집합이 **TLB 도달 범위** 초과로 미스 증가 | **대형 페이지**·페이지 배치 최적화 | 변환 미스·워크 횟수 감소 |
| 문맥 전환마다 전체 TLB 플러시 비용 | **ASID**·**선택적 무효화** 적용 | 전환 직후 미스 급증 완화 |
| 다단계 순회 반복으로 메모리 지연 증가 | **페이지 워크 캐시** 적용 | 순회 메모리 접근·지연 감소 |
| 대형 페이지의 **내부 단편화** | 큰 연속 할당 영역에만 선택 적용 | 커버리지 이득과 공간 낭비 균형 |

#### 한줄 요약
- 대책 넷 중 셋이 TLB 바깥을 손대는 이유는 TLB가 전가산 비교 구조라 용량을 늘리면 적중 시간이 곧바로 나빠지기 때문이다.

## Ⅶ. 결론

- 작업 집합이 도달 범위를 넘으면 **대형 페이지**, 문맥 전환이 잦으면 **ASID**를 적용하되, 세밀한 보호·메모리 절약이 우선인 영역은 기본 페이지 유지

#### 한줄 요약
- 대형 페이지는 변환 비용과 메모리 낭비를 맞바꾸는 선택이므로, 메모리가 넉넉할 때만 이득이고 빠듯하면 **내부 단편화**로 되돌아온다.
