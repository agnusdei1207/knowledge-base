## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **변환 참조 버퍼(Translation Lookaside Buffer, TLB)**: 가상 주소를 물리 주소로 고속 변환하기 위해 최근 사용된 페이지 테이블 매핑(VPN-PPN)을 저장하는 MMU 내부의 특수 하드웨어 캐시.
- **가상 페이지 번호(Virtual Page Number, VPN)**: 가상 주소(VA)에서 페이지 오프셋을 제외한 상위 비트 필드로, 페이지 테이블 검색 및 TLB 태그 비교의 기준이 되는 식별자.
- **물리 페이지 번호(Physical Page Number, PPN)**: 주소 변환 결과로 도출되는 실제 물리 메모리(DRAM)의 프레임 기준 번호(Page Frame Number, PFN).
- **내용 주소화 기억장치(Content Addressable Memory, CAM)**: 주소 대신 데이터 내용(VPN 태그)을 입력받아 전체 엔트리를 단 1클록 만에 동시 병렬 비교하여 매핑된 출력(PPN)을 도출하는 고속 연관 하드웨어 메모리.

</details>

- 정의/개념: **가상 페이지 번호(VPN)** 및 **물리 페이지 번호(PPN)** 대응을 캐싱해 재순회를 없애는 **메모리 관리 장치(MMU)** 내부 캐시
- 배경/필요성: 주소 변환 캐싱 없이는 **다단계 페이지 테이블 순회에 따른 메모리 접근 오버헤드 불가피**

#### 한줄 요약
- **TLB는** 데이터 캐시와 달리 미스 한 번에 메모리 접근이 여러 번 따라붙으므로, 같은 미스율이라도 성능에 미치는 타격이 훨씬 크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리에 각 프로세스의 고유 프로세스 ID를 태깅하여, 문맥 전환(Context Switch) 시 TLB 전체 플러시 없이 복수 프로세스의 엔트리가 공존하도록 하는 식별자.
- **TLB 도달 범위(TLB Reach)**: TLB 전체 엔트리 수와 각 엔트리가 매핑하는 페이지 크기의 곱($TLB\,Entries \times Page\,Size$)으로 계산되는, TLB가 메모리 접근 시 미스 없이 직접 커버할 수 있는 총 가상 메모리 용량.
- **대형 페이지(Huge Page)**: 표준 4KB 페이지 대신 2MB, 1GB 등 대용량 페이지 단위를 사용하여 동일한 TLB 엔트리 수로 TLB 도달 범위를 획기적으로 확장하는 기법.

</details>

- 최근 변환을 재사용해 페이지 테이블 순회 횟수를 줄이고 주소 변환 지연 단축
- **ASID** 태깅으로 문맥 전환 시 TLB 플러시 없이 다수 프로세스 엔트리 공존
- **대형 페이지** 적용으로 단일 엔트리가 커버하는 **TLB 도달 범위** 확대

#### 한줄 요약
- **TLB 도달 범위는** 엔트리 수와 페이지 크기의 곱이라는 점이 핵심이며, 엔트리를 늘리는 것보다 페이지를 키우는 쪽이 훨씬 싸게 같은 효과를 낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 중지하고 메모리 상의 다단계(Multi-level) 페이지 테이블을 계층적으로 순회(Page Walk)하여 변환 정보를 인출하는 하드웨어 유닛.
- **CAM 회로 (Content Addressable Memory)**: TLB 조회기 내부에 탑재되어 모든 TLB 엔트리의 VPN 태그를 1클록 내에 병렬 전수 비교하는 하드웨어 회로.

</details>

```text
[MMU 주소 변환 구조]
├─ TLB 조회기 (CAM 병렬 비교 회로)
│  └─ TLB 엔트리 (VPN·ASID / PPN / 권한·유효 비트)
└─ 페이지 테이블 워커
   └─ 페이지 테이블 (메모리 내)
```

선의 의미: 가지(`├─`)는 소유·연결 관계; 페이지 테이블 워커와 페이지 테이블은 TLB 미스 경로에서만 활성화

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **TLB 조회기 (CAM)** | **CAM(내용 주소화 기억장치)** 회로로 VPN·**ASID**를 전 엔트리와 동시 병렬 비교 | 1클록 고속 적중 판정 |
| **TLB 엔트리** | 가상 페이지 태그(VPN), 물리 프레임(PPN), **ASID**, 권한 및 유효 비트 보관 | 전연관 매핑 저장소 |
| **페이지 테이블 워커** | TLB 미스 발생 시 메모리의 **다단계 페이지 테이블(Page Table)을 계층 순회** | 하드웨어 미스 처리 |
| **페이지 테이블** | OS 커널이 관리하는 **가상 주소 공간과 물리 메모리 프레임 간 전체 매핑 정본** | DRAM 상주 데이터 |

#### 한줄 요약
- 워커가 하드웨어에 들어온 덕분에 미스가 예외가 아니라 지연으로 바뀌었고, CAM 병렬 비교 회로를 통해 1클록 적중을 보장한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: CPU가 요청한 가상 페이지 번호(VPN)와 ASID가 TLB 내에 유효하게 존재하여 추가 메모리 접근 없이 단일 클록 내에 물리 주소(PPN)를 생성하는 상태.
- **TLB 미스(TLB Miss)**: 요청된 VPN의 변환 엔트리가 TLB에 존재하지 않아 하드웨어 페이지 테이블 워커가 메모리의 페이지 테이블을 순회해야 하는 상태.
- **페이지 폴트(Page Fault)**: 주소 변환 과정에서 요청된 페이지가 물리 메모리에 상주하지 않거나(Present=0), 접근 권한(R/W/X)을 위반하여 OS 커널의 예외 처리 루틴으로 제어가 전환되는 하드웨어 인터럽트.

</details>

```text
가상 주소 입력
      │
      ▼
1. VPN 및 ASID TLB CAM 병렬 조회
      │
      ├─ 적중 (TLB Hit) → PPN·오프셋 결합 → 물리 주소 생성 (1클록 완료)
      │
      └─ 미스 (TLB Miss)
             │
             ▼
      2. 페이지 테이블 워커 다단계 메모리 순회 (Page Walk)
             │
             ├─ 유효 매핑 → TLB CAM 리필 → 물리 주소 생성
             │
             └─ 부재·권한 오류 → 3. 페이지 폴트 예외 발생 → OS 인터럽트 핸들러 처리
```

분기 결과: **TLB 적중은** 클록 단위로 끝나고 **TLB 미스는** 메모리 접근 단위로 끝나지만, **페이지 폴트**만은 저장장치 단위라 세 경로의 비용 차이가 자릿수 단위로 벌어짐

#### 한줄 요약
- 세 경로가 모두 같은 한 번의 메모리 참조에서 갈리기 때문에, 프로그램 입장에서는 예측할 수 없는 지연 편차로 나타난다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLB 미스(TLB Miss)**: 하드웨어 워커가 페이지 테이블을 순회하여 TLB를 리필하는 하드웨어 지연 사건.
- **페이지 폴트(Page Fault)**: 대상 페이지가 물리 메모리에 없어 OS가 디스크에서 페이지를 반입하는 소프트웨어 트랩 예외 사건.

</details>

| 주소 변환 사건 | TLB 미스 (TLB Miss) | 페이지 폴트 (Page Fault) |
|:---|:---|:---|
| 적용 기준 | **유효 매핑은 있으나 TLB에 캐싱되지 않음** | **페이지 부재(Present=0) 또는 접근 권한 위반** |
| 핵심 특징 | **하드웨어 워커가 순회 후 TLB CAM 리필 및 재개** | **OS 커널 인터럽트로 스왑 적재·권한 변경 후 재시도** |
| 한계 | 페이지 테이블 깊이(4단계)만큼 메모리 접근 지연 (수십 ns)| 디스크/스토리지 I/O 접근으로 인한 초장시간 지연 (수 ms) |
| 처리 주체 | **하드웨어 (MMU Page Table Walker)** | **소프트웨어 커널 (OS Page Fault Handler)** |

#### 한줄 요약
- 둘은 같은 미스처럼 보이지만 처리 주체가 하드웨어와 소프트웨어로 갈리며, 그 경계가 곧 성능 문제와 정합성 문제의 경계가 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페이지 워크 캐시(Page Walk Cache)**: 다단계 페이지 테이블 순회 시 상위 단계(PML4, PDP, PD 등) 디렉터리 엔트리의 주소 변환 결과를 별도로 캐싱하여 순회 지연시간을 단축하는 특수 캐시.
- **선택적 무효화(Selective Invalidation)**: 특정 프로세스의 종료나 메모리 해제(munmap) 시 전체 TLB를 비우지 않고 해당 가상 주소 범위 또는 ASID에 해당하는 특정 엔트리만 선별하여 무효화하는 명령어(INVLPG, TLBI 등).
- **내부 단편화(Internal Fragmentation)**: 대형 페이지 할당 시 실제 프로세스가 필요로 하는 메모리보다 큰 고정 블록이 할당되어 페이지 내부에서 사용되지 않고 낭비되는 메모리 공간.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 워크로드 실행 시 **TLB 도달 범위** 초과로 미스 급증 | **대형 페이지(Huge Page: 2MB/1GB)** 및 메모리 배치 최적화 | 변환 미스 및 Page Walk 횟수 대폭 감소 |
| 문맥 전환마다 전체 TLB 플러시로 인한 파이프라인 지연 | **ASID 태깅** 및 **선택적 무효화(INVLPG)** 명령어 적용 | 전환 직후 콜드 미스 완화 및 캐시 보존 |
| 4~5단계 다단계 순회 반복으로 메모리 지연 오버헤드 누적 | **페이지 워크 캐시(Page Walk Cache)** 하드웨어 활성화 | 상위 디렉터리 재참조 생략 및 워크 지연 단축 |
| 대형 페이지 도입 시 프로세스 메모리의 **내부 단편화** 발생 | 대규모 연속 메모리(DB 버퍼 풀 등)에만 **선택적 대형 페이지 적용** | TLB 적중률 향상과 DRAM 낭비의 균형 달성 |

#### 한줄 요약
- 대책 넷 중 셋이 TLB 바깥을 손대는 이유는 TLB가 CAM 전가산 병렬 비교 구조라 용량을 무작정 늘리면 클록 적중 시간이 곧바로 저하되기 때문이다.

## Ⅶ. 결론

- 초고속 메모리 가상화를 달성하기 위해 **CAM 기반의 TLB 하드웨어 캐싱과 1클록 주소 변환을 보장**하고, **대규모 데이터베이스 워크로드에는 대형 페이지(Huge Page)와 ASID 태깅 및 페이지 워크 캐시**를 결합하여 주소 변환 오버헤드를 극소화하는 메모리 아키텍처 확립

#### 한줄 요약
- TLB는 CAM 병렬 비교 회로를 통해 가상 주소를 1클록 만에 변환하며, 대형 페이지와 ASID를 결합하여 성능을 극대화하는 핵심 MMU 캐시 기술이다.
