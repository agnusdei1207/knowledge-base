## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 관리 장치(Memory Management Unit, MMU)**: CPU 내부에 위치하여 가상 주소의 물리 주소 변환, 메모리 보호 및 접근 권한 검증을 하드웨어적으로 전담하는 핵심 장치.
- **변환 참조 버퍼(Translation Lookaside Buffer, TLB)**: CPU 내부 MMU에 탑재되어 최근 사용된 페이지 매핑(VPN-PPN)을 저장함으로써 다단계 페이지 테이블 순회를 생략시키는 고속 주소 변환 캐시.
- **내용 주소화 기억장치(Content Addressable Memory, CAM)**: TLB 하드웨어 내부에 내장되어, 입력된 가상 페이지 번호(VPN)를 전체 엔트리와 단 1클록 만에 동시 병렬 비교하는 고속 연관 검색 회로.
- **가상 페이지 번호(Virtual Page Number, VPN)**: 프로세스 가상 주소(VA)에서 오프셋을 제외한 상위 비트 필드로, TLB의 CAM 태그 비교 및 페이지 테이블 탐색의 기준이 되는 식별자.
- **물리 페이지 번호(Physical Page Number, PPN)**: 주소 변환 결과로 도출되어 오프셋과 결합하는 실제 메인 메모리(DRAM)의 프레임 기준 번호(Page Frame Number, PFN).

</details>

- 정의/개념: 가상 메모리 시스템에서 페이지 테이블 순회 지연을 제거하기 위해 최근 참조된 가상-물리 주소 변환 매핑(VPN-PPN)을 보관하는 하드웨어 **주소 변환 캐시**
- 배경/필요성: 가상 메모리 환경에서 매 메모리 접근 시마다 4~5단계의 다단계 페이지 테이블을 순회(Page Walk)함에 따른 심각한 **DRAM 접근 지연** 및 버스 병목을 해소하기 위해 1클록 변환 메커니즘 필수화

#### 한줄 요약
- TLB는 CPU 내부 MMU에 위치하는 주소 변환 전용 캐시로, 데이터 캐시와 달리 미스 발생 시 다단계 메모리 순회가 수반되므로 성능 영향이 매우 크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **주소 공간 식별자(Address Space Identifier, ASID)**: TLB 엔트리에 각 프로세스 고유 식별자를 태깅하여, 문맥 전환(Context Switch) 시 TLB 전체 플러시 없이 복수 프로세스 엔트리의 공존을 보장하는 태그.
- **TLB 도달 범위(TLB Reach)**: TLB 전체 엔트리 수와 페이지 크기의 곱($TLB\,Entries \times Page\,Size$)으로 결정되는, TLB가 미스 없이 직접 매핑할 수 있는 총 가상 메모리 용량.
- **대형 페이지(Huge Page)**: 표준 4KB 페이지 대신 2MB, 1GB 등 대용량 페이지 단위를 적용하여 동일한 TLB 엔트리 수로 TLB 도달 범위를 획기적으로 확장하는 기법.

</details>

- 순회 지연 생략: MMU 내부 TLB 캐싱을 통해 **다단계 페이지 테이블 순회**를 생략하고 1클록 내 가상-물리 주소 변환 완료
- 문맥 전환 최적화: 엔트리별 **ASID** 태깅을 통해 프로세스 전환 시 전체 TLB 플러시를 방지하고 다중 주소 공간 공존 지원
- 도달 범위 확장: **대형 페이지** 기법을 적용하여 물리적 엔트리 수 증가 없이 **TLB 도달 범위**를 수십 배에서 수백 배까지 확장

#### 한줄 요약
- TLB 도달 범위는 엔트리 수와 페이지 크기의 곱으로 결정되며, 회로 면적 한계상 엔트리를 늘리기보다 대형 페이지를 적용하는 것이 유리하다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **페이지 테이블 워커(Page Table Walker)**: TLB 미스 발생 시 CPU 파이프라인을 일시 중지하고 메모리 상의 다단계(Multi-level) 페이지 테이블을 계층적으로 순회(Page Walk)하여 변환 정보를 인출하는 MMU 내부 하드웨어 유닛.
- **SRAM 엔트리 배열**: CAM 회로의 병렬 태그 비교 적중 신호에 따라 대응하는 물리 페이지 번호(PPN)와 제어 비트를 즉시 출력하는 저장 셀 배열.

</details>

```text
[메모리 관리 장치 (MMU)]
  │
  ├─ [변환 참조 버퍼 (TLB)]
  │     ├─ [CAM 비교기] (VPN·ASID 병렬 매칭)
  │     └─ [SRAM 엔트리] (PPN·접근 권한 R/W/X)
  │
  ├─ [페이지 테이블 워커] (미스 시 하드웨어 자동 순회)
  │
  └─ [주기억장치 (DRAM)]
        └─ [다단계 페이지 테이블] (커널 매핑 정본)
```

선의 의미: MMU 내부 TLB(CAM·SRAM), 페이지 테이블 워커 및 주기억장치 페이지 테이블의 계층 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| MMU | 가상-물리 주소 변환 실행 및 메모리 접근 보호 권한(R/W/X) 하드웨어 검증 |
| TLB (CAM+SRAM) | 최근 사용된 **VPN-PPN 매핑**을 보관하여 단일 사이클 주소 변환 완료 |
| CAM 병렬 비교기 | 입력된 VPN 및 **ASID**를 전체 엔트리와 동시 비교하여 적중 여부 판정 |
| 페이지 테이블 워커 | TLB 미스 발생 시 DRAM의 **다단계 페이지 테이블**을 자율 계층 순회 |
| 페이지 테이블 | 운영체제 커널이 관리하는 프로세스 가상 메모리 매핑 정본 정보 보관 |

#### 한줄 요약
- CPU 내 MMU가 TLB(CAM+SRAM)와 하드웨어 워커를 내장함으로써, 1클록 고속 주소 변환과 미스 시 자동 계층 순회를 모두 하드웨어 레벨에서 완결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TLB 적중(TLB Hit)**: CPU가 요청한 가상 페이지 번호(VPN)가 MMU 내 TLB(CAM)에서 1클록 만에 일치하여 메모리 접근 없이 물리 주소를 도출하는 상태.
- **TLB 미스(TLB Miss)**: 요청된 VPN이 TLB에 존재하지 않아 MMU의 하드웨어 페이지 테이블 워커가 DRAM 상의 페이지 테이블 순회를 개시하는 지연 상태.
- **페이지 폴트(Page Fault)**: 페이지 테이블 순회 결과 물리 메모리에 대상 페이지가 부재(Present=0)하거나 권한을 위반하여 OS 커널 트랩 핸들러로 제어가 전환되는 예외.

</details>

```text
[CPU 가상 주소(VA) 발생]
            │
            ▼
1. TLB 병렬 태그 비교
   ┌────────┴────────┐
(TLB 적중: Hit)   (TLB 미스: Miss)
   │                 │
   │                 ▼
   │      2. 다단계 페이지 테이블 순회
   │                 ┌────────┴────────┐
   │          (매핑 유효)       (부재 / 권한 위반)
   │                 │                 │
   │                 ▼                 ▼
   │          TLB 엔트리 리필   3. 페이지 폴트 발생
   │                 │                 │
   ▼                 ▼                 ▼
[물리 주소 생성 완료]           [OS 커널 핸들러 처리]
```

분기 결과: **TLB 적중**은 1클록 단위 완결, **TLB 미스**는 메모리 버스 지연 수반, **페이지 폴트**는 디스크 I/O로 인한 초장시간 지연 발생

**동작 원리**

1. **TLB 병렬 태그 비교**: CPU가 가상 주소(VA)를 발생시키면 MMU 내 TLB의 CAM 회로가 가상 페이지 번호(VPN) 및 ASID를 전체 엔트리와 동시 병렬 비교함
2. **다단계 페이지 테이블 순회**: TLB 미스 발생 시 하드웨어 페이지 테이블 워커가 CR3 레지스터를 기점으로 DRAM 상의 다단계 페이지 테이블을 계층 순회하여 변환 엔트리를 인출하고 TLB를 리필함
3. **페이지 폴트 발생**: 순회 도중 대상 페이지의 유효 비트가 부재(Present=0)하거나 접근 권한 위반 감지 시 하드웨어 인터럽트를 발생시켜 OS 커널 페이지 폴트 핸들러로 제어를 전환함

#### 한줄 요약
- 세 경로는 동일한 단일 메모리 참조에서 분기하지만, 하드웨어 1클록 캐시 적중에서부터 소프트웨어 디스크 I/O 트랩까지 지연시간이 자릿수 단위로 격차를 보인다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLB 미스(TLB Miss)**: 하드웨어 워커가 페이지 테이블을 순회하여 TLB를 리필하는 MMU 하드웨어 레벨 지연 사건.
- **페이지 폴트(Page Fault)**: 대상 페이지가 DRAM에 없어 OS가 보조기억장치에서 페이지를 반입하는 운영체제 커널 레벨 예외 사건.

</details>

| 주소 변환 사건 | TLB 미스 (TLB Miss) | 페이지 폴트 (Page Fault) |
|:---|:---|:---|
| 적용 기준 | **DRAM 상 매핑 존재**하나 TLB 미캐싱 시 | **물리 메모리 내 페이지 부재** 또는 권한 위반 시 |
| 핵심 특징 | **MMU 하드웨어 워커** 순회 및 단일 사이클 리필 | **OS 커널 인터럽트** 트랩 및 스토리지 스왑 반입 |
| 한계 | 다단계 페이지 테이블 깊이만큼의 **DRAM 접근 지연** | 디스크 I/O 유발에 따른 **밀리초 단위 파이프라인 중단** |

#### 한줄 요약
- TLB 미스는 CPU 내부 MMU 하드웨어가 자체 해결하는 지연 사건이고, 페이지 폴트는 OS 커널이 스토리지 I/O로 해결하는 시스템 예외 사건이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **페이지 워크 캐시(Page Walk Cache)**: MMU 내부에 위치하여 다단계 페이지 테이블 순회 시 상위 디렉터리(PML4, PDP 등) 변환 결과를 별도 캐싱하는 하드웨어 캐시.
- **선택적 무효화(Selective Invalidation)**: 프로세스 종료나 메모리 해제 시 전체 TLB를 플러시하지 않고 특정 가상 주소나 ASID 엔트리만 선별 무효화하는 명령어(INVLPG, TLBI 등).
- **내부 단편화(Internal Fragmentation)**: 대형 페이지 할당 시 실제 프로세스가 요구하는 메모리보다 큰 고정 블록이 할당되어 페이지 내부 공간이 낭비되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 메모리 워크로드 실행 시 **TLB 도달 범위** 초과 및 미스 급증 | **대형 페이지(Huge Page)** 적용 및 연속 메모리 할당 | TLB 엔트리당 커버 용량 증대로 Page Walk 빈도 대폭 감소 |
| 문맥 전환 시 전체 TLB 플러시로 인한 콜드 미스 지연 | **ASID 태깅** 및 **선택적 무효화(INVLPG)** 적용 | 문맥 전환 후에도 기존 프로세스 엔트리 유지로 초기 변환 지연 완화 |
| 다단계 페이지 테이블 순회로 메모리 버스 트래픽 누적 | 하드웨어 **페이지 워크 캐시** 활성화 | 상위 디렉터리 재순회 생략 및 워크 지연 시간 단축 |

#### 한줄 요약
- TLB는 CAM 병렬 회로 특성상 용량을 무한정 늘릴 수 없으므로, 대형 페이지와 ASID 및 페이지 워크 캐시를 결합하여 실무 성능 한계를 극복한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **확장 페이지 테이블(Extended Page Table, EPT)**: 가상화 환경에서 게스트 물리 주소를 호스트 물리 주소로 2단계 변환하는 하드웨어 가속 페이지 테이블.
- **투명한 대형 페이지(Transparent Huge Pages, THP)**: 애플리케이션의 소스 코드 수정 없이 OS 커널 백그라운드 데몬이 자동으로 2MB 대형 페이지를 할당·병합하는 관리 기술.

</details>

- 가상-물리 주소 변환 지연을 1클록 내로 단축하는 필수 하드웨어 캐시로서 모든 현대 프로세서 MMU에 표준 안착되었으며, 테라바이트급 메모리를 활용하는 가상화 및 대규모 AI 학습 환경에서는 중첩 변환 지연을 줄이기 위해 **확장 페이지 테이블(EPT)** 하드웨어 가속 및 2MB/1GB 대형 페이지 계층 구조로 진화하는 추세.
- 대형 페이지 도입은 TLB 도달 범위를 극대화하지만 메모리 내부 단편화와 **투명한 대형 페이지(THP)** 동적 콤팩션에 따른 레이턴시 스파이크를 초래할 수 있으므로, 데이터베이스·AI 파이프라인의 접근 패턴에 맞추어 정적 대형 페이지 할당과 TLB 엔트리 정책을 조율하는 실무 엔지니어링 역량 확보 필요.

#### 한줄 요약
- TLB는 EPT 가속 및 대형 페이지 결합을 통해 가상화·AI 병목을 극복하며, 메모리 단편화와 콤팩션 지연을 통제하는 워크로드별 페이지 크기 최적화가 필수적이다.
