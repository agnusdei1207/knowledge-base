## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **독립 디스크 중복 배열(Redundant Array of Independent Disks, RAID)**: 여러 디스크에 데이터를 분산하거나 중복해 처리량과 장애 가용성을 조절하는 구성이다.
- **가용성**: 일부 디스크 장애 중에도 배열이 읽기•쓰기 서비스를 계속 제공하는 성질이다.

</details>

- 정의/개념: 여러 디스크에 데이터를 분산하거나 중복해 처리량·용량·장애 허용성을 조절하는 **RAID** 구성이다.
- 배경/필요성: 단일 디스크만으로는 병렬 처리량을 늘리거나 장치 장애 중 **가용성**을 유지하기 어렵다.

#### 한줄 요약

- RAID는 스트라이핑으로 디스크 병렬성을 활용하고 미러·패리티로 멤버 장애 중 데이터 접근을 유지한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **스트라이핑**: 데이터를 조각으로 나눠 여러 멤버 디스크에 병렬 배치하는 방식이다.
- **미러링**: 같은 데이터를 여러 디스크에 복제하는 방식이다.
- **패리티**: 남은 데이터로 손실분을 계산할 중복 정보를 저장하는 방식이다.
- **읽기-수정-쓰기**: 작은 패리티 쓰기에서 기존 데이터•패리티를 읽고 새 값을 다시 기록하는 절차이다.

</details>

- 디스크 병렬 처리량을 확대하는 **스트라이핑**이 핵심이다.
- 멤버 장애 중 서비스를 지속하는 **미러•패리티**가 핵심이다.
- 패리티 쓰기 패널티를 만드는 **읽기-수정-쓰기**가 핵심이다.

#### 한줄 요약

- RAID는 멤버 디스크 장애 중 서비스를 유지하지만 삭제·변조·배열 전체 손실을 복구하는 독립 백업은 대체하지 못한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **RAID 컨트롤러**: 논리 블록 매핑과 중복•장애•재구축을 제어하는 구성요소이다.
- **스트라이프 매퍼**: 호스트 논리 블록을 멤버 디스크와 오프셋으로 변환하는 구성요소이다.
- **배타적 논리합(Exclusive OR, XOR)**: 패리티 생성과 손실 데이터 복원에 사용하는 논리 연산이다.
- **중복 엔진**: 미러 복제와 XOR 패리티 생성•복원을 수행하는 구성요소이다.
- **입출력(Input/Output, I/O)**: 호스트와 디스크 배열 사이의 데이터를 전달하는 경로이다.

</details>

```text
              [RAID 컨트롤러]
                 /        \
    [스트라이프 매퍼]   [중복 엔진]
                 \        /
        [멤버 디스크•장애 도메인]
```

선의 의미: RAID 컨트롤러가 스트라이프 매퍼와 중복 엔진을 소유하고 두 내부 기능이 같은 멤버 디스크 집합에 접하는 정적 제어•연결 관계다.

| 구성요소 | 책임 |
|:---|:---|
| RAID 컨트롤러 | 호스트 I/O•배열 장애 제어 |
| 스트라이프 매퍼 | 논리 블록의 멤버•오프셋 변환 |
| 중복 엔진 | 미러•패리티 생성•데이터 복원 |
| 멤버 디스크•장애 도메인 | 데이터•중복 블록의 독립 저장 |

#### 한줄 요약

- 컨트롤러가 블록 위치를 정하고 중복 엔진이 미러•패리티를 만들어 독립 디스크에 저장한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **부분 스트라이프 쓰기**: 한 스트라이프 전체보다 작은 데이터만 갱신해 기존 패리티 조회가 필요한 쓰기이다.
- **XOR 패리티**: 여러 데이터 블록의 XOR로 생성해 손실 블록을 복원하는 값이다.
- **쓰기 완료 원자성**: 데이터와 패리티가 모두 반영돼 서로 일치한 뒤 호스트에 완료를 알리는 성질이다.
- **멤버 위치 결정**: 논리 블록 주소로 데이터와 패리티를 저장할 디스크를 정하는 단계이다.
- **기존 데이터·패리티 조회**: 부분 스트라이프 갱신에 필요한 이전 값과 패리티를 읽는 단계이다.
- **새 패리티 계산**: 이전 데이터·패리티와 변경 데이터를 XOR해 갱신 패리티를 만드는 단계이다.
- **데이터·패리티 기록**: 변경 데이터와 새 패리티를 각 멤버에 반영하는 단계이다.

</details>

```text
                   [부분 스트라이프 쓰기]
                              |
                     1. 멤버 위치 결정
                              |
           +-----------------------------------+
           | 병렬: 기존 데이터•패리티 멤버   |
           | 2. 기존 데이터•패리티 조회      |
           +-----------------------------------+
                              |
                    3. XOR 패리티 재계산
                              |
           +-----------------------------------+
           | 병렬: 데이터•패리티 멤버        |
           | 4. 변경 데이터•패리티 기록      |
           +-----------------------------------+
                              |
                       [모두 기록 완료?]
                         /           \
                      [아니요]        [예]
                         |             |
                  [저널 기반 복구]  [쓰기 완료]
```

### 동작 원리

1. **멤버 위치 결정**: 논리 블록 주소로 변경 데이터와 분산 패리티를 저장할 멤버 디스크를 지정한다.
2. **기존 데이터·패리티 조회**: 부분 스트라이프 갱신에 필요한 이전 데이터와 XOR 패리티를 읽는다.
3. **새 패리티 계산**: 이전 데이터·패리티와 변경 데이터를 XOR해 갱신 패리티를 생성한다.
4. **데이터·패리티 기록**: 변경 데이터와 새 패리티를 각 멤버에 기록하고 **쓰기 완료 원자성**을 확인한 뒤 호스트에 완료를 통지한다.

#### 한줄 요약

- RAID 5의 부분 스트라이프 쓰기는 기존 데이터·패리티를 읽어 새 패리티를 계산하고, 변경 데이터와 패리티가 모두 기록된 뒤 완료한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **RAID 0**: 중복 없이 데이터를 여러 디스크에 스트라이핑한 구성이다.
- **RAID 1**: 같은 데이터를 두 디스크에 미러링한 구성이다.
- **RAID 5**: 단일 분산 패리티로 한 디스크 장애를 허용하는 구성이다.
- **RAID 6**: 이중 분산 패리티로 두 디스크 장애를 허용하는 구성이다.
- **RAID 10**: 미러 쌍을 다시 스트라이핑한 구성이다.
- **사용 가능 용량**: 중복 정보에 쓰는 공간을 제외하고 호스트 데이터에 사용할 수 있는 총용량이다.
- **용량 효율**: 전체 디스크 원시 용량 중 사용 가능 용량이 차지하는 비율이다.
- **허용 장애 수**: 데이터 손실 없이 동시에 고장 날 수 있는 멤버 디스크의 최대 개수이다.
- **쓰기 패널티**: 한 논리 쓰기에 추가로 필요한 패리티 계산과 디스크 입출력 부담이다.

</details>

| RAID 레벨 | RAID 0 | RAID 1 | RAID 5 | RAID 6 | RAID 10 |
|:---|:---|:---|:---|:---|:---|
| 적용 기준 | 손실되어도 다시 만들 수 있는 임시 데이터 | 단순한 복제와 빠른 장애 전환이 필요할 때 | 읽기 중심이며 **용량 효율**이 중요할 때 | 대형 배열에서 **허용 장애 수**가 2개여야 할 때 | 작은 쓰기가 많은 데이터베이스 |
| 핵심 특징 | 스트라이핑•용량 \(N S\) | 미러링•용량 \(S\) | 단일 패리티•용량 \((N-1)S\) | 이중 패리티•용량 \((N-2)S\) | 미러 쌍•용량 \(NS/2\) |
| 한계 | 한 멤버 장애 시 전체 손실 | 사용 가능 용량 절반 | 작은 쓰기의 패리티 갱신 | 이중 패리티 **쓰기 패널티** | 같은 미러 쌍 동시 장애 |

> 용량식은 동일 용량 디스크를 가정

> 요약: 처리량•**사용 가능 용량** 및 **허용 장애 수**를 기준으로 레벨을 선택한다.

#### 한줄 요약

- 재생성 가능한 데이터는 RAID 0, 단순 복제는 RAID 1, 용량 효율과 단일·이중 장애 허용은 RAID 5·6, 쓰기 집중 부하는 RAID 10을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **재구축**: 중복 정보로 교체 멤버의 데이터를 복원하는 작업이다.
- **핫 스페어**: 장애 멤버를 즉시 대체할 대기 디스크이다.
- **쓰기 구멍**: 정전이나 부분 실패로 데이터와 패리티 중 일부만 기록돼 서로 불일치하는 문제이다.
- **장애 도메인**: 전원•섀시처럼 구성요소가 함께 고장 날 수 있는 경계이다.
- **백업**: 삭제•변조•배열 전체 손실에 대비한 독립 데이터 사본이다.
- **순찰 읽기**: 모든 멤버의 블록을 주기적으로 읽어 잠재 오류를 미리 찾는 검사이다.
- **쓰기 저널**: 데이터와 패리티 갱신 의도를 먼저 기록해 부분 쓰기 뒤 복구할 수 있게 하는 로그이다.
- **배터리 보호 캐시**: 정전 시에도 대기 중인 쓰기 데이터를 보존하는 컨트롤러 캐시이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 재구축이 길어져 남은 멤버의 추가 장애 위험 증가 | **핫 스페어·순찰 읽기**와 서비스 영향을 고려한 재구축 우선순위 설정 | 장애 발견·교체를 앞당겨 재구축 취약 시간 단축 |
| 정전·부분 쓰기로 데이터와 패리티가 서로 다른 시점의 값 | **쓰기 저널·배터리 보호 캐시**와 패리티 일관성 검사 | 원자적 복구로 **쓰기 구멍** 방지 |
| 미러·패리티 멤버가 같은 전원·섀시에 있어 상관 장애 발생 | 중복 멤버를 **장애 도메인**별로 분산 | 공통 원인 장애에도 중복 데이터 생존 |
| RAID를 백업으로 오인해 삭제·변조·배열 손실 복구 불가 | 별도 장애 도메인의 **백업**과 정기 복원 시험 | 논리 오류와 배열 전체 손실 대응 |

> 사례: RAID 10으로 패리티 갱신 제거

#### 한줄 요약

- 쓰기 집중 워크로드에는 RAID 10을 적용하고, 각 미러 쌍은 공통 장애를 피하도록 서로 다른 장애 도메인에 배치한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **쓰기 집중 워크로드**: 작은 갱신이 빈번해 패리티 계산과 쓰기 패널티가 성능을 제한하는 작업이다.
- **이중 장애 허용**: 서로 다른 두 멤버가 동시에 고장 나도 데이터를 복원하고 서비스를 유지하는 능력이다.
- **RAID 선택 기준**: 쓰기 특성·용량 효율·허용 장애 수로 RAID 레벨을 고르는 기준이다.

</details>

- **RAID 선택 기준**에 따라 **쓰기 집중 워크로드**에는 **RAID 10**, **이중 장애 허용**에는 **RAID 6**을 선택한다.

#### 한줄 요약

- 잦은 쓰기는 미러 쌍을, 긴 재구축 중 두 고장까지 버텨야 하면 이중 패리티를 선택한다.
