## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RAID(Redundant Array of Independent Disks)**: 복수의 물리 드라이브를 단일 논리 스토리지 어레이로 결합하고 스트라이핑(성능), 미러링(복제), 패리티(오류 복구) 기술을 조합하여 고속 I/O 대역폭과 내고장성을 제공하는 스토리지 가상화 기술.
- **고가용성(High Availability)**: 단일 디스크의 물리적 파손이 발생하더라도 시스템 중단 없이 정상적인 읽기/쓰기 서비스를 지속할 수 있는 신뢰성 능력.

</details>

- 정의/개념: 복수의 물리 디스크를 논리 어레이로 묶고 **스트라이핑(성능), 미러링(복제), 패리티(잉여 연산)** 기술을 최적 조합하여 성능과 내고장성을 조절하는 **RAID 스토리지 아키텍처**
- 배경/필요성: 단일 드라이브 사용에 따른 **I/O 대역폭 병목 및 물리 디스크 고장 시 데이터 유실 및 서비스 전면 중단 방지**

#### 한줄 요약
- RAID는 여러 디스크를 하나로 묶어 스트라이핑으로 속도를 높이고 미러링/패리티로 장애를 방어하는 스토리지 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 데이터를 고정 크기 블록 단위로 쪼개어 복수의 디스크에 병렬로 분산 기록함으로써 총 I/O 대역폭을 극대화하는 기법.
- **미러링(Mirroring)**: 동일한 데이터 블록을 2개 이상의 독립 디스크에 1:1 완전 복제하여 완벽한 데이터 중복성을 확보하는 기법.
- **패리티(Parity)**: 데이터 블록 간 XOR 논리 연산을 통해 생성한 복구용 잉여 데이터로, 디스크 1~2개 고장 시 손실된 원본을 수학적으로 복원하는 기법.

</details>

- 입출력 대역폭 극대화: **스트라이핑(Striping)**을 통해 다수 디스크의 헤드와 채널을 동시 구동하여 순차 및 랜덤 I/O 처리량 선형 확장
- 무중단 데이터 복구: **미러링(Mirroring)** 또는 **패리티(Parity)** 연산을 통해 디스크 고장 시에도 실시간 데이터 역산 복구 및 고가용성 제공
- 쓰기 오버헤드와 용량 절충: 높은 신뢰성을 위해 패리티 계산(XOR/Reed-Solomon)에 따른 쓰기 페널티나 미러링에 따른 50% 용량 손실을 절충

#### 한줄 요약
- 스트라이핑은 성능을, 미러링과 패리티는 안정성을 제공하며, 용량 효율과 쓰기 속도 간의 상충 관계를 갖는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RAID 컨트롤러(RAID Controller / HBA)**: 호스트 입출력 요청을 받아 LBA 스트라이프 매핑, 패리티 연산, 쓰기 캐시 관리, 디스크 장애 감시를 전담하는 하드웨어 ASIC.
- **배터리 백업 장치(Battery Backup Unit, BBU / SuperCap)**: 정전 시 컨트롤러의 휘발성 DRAM 쓰기 캐시에 잔류한 데이터를 비휘발성 플래시로 안전하게 덤프할 수 있도록 전력을 공급하는 모듈.

</details>

```text
[호스트 서버 (OS 파일 시스템)]
       │ (PCIe / SAS / NVMe 버스)
       ▼
[하드웨어 RAID 컨트롤러 (ASIC)]
 ├─ 스트라이프 주소 매퍼 (LBA ➔ 물리 디스크 채널 / 오프셋 변환)
 ├─ 하드웨어 패리티 가속기 (XOR & Reed-Solomon 엔진)
 ├─ DRAM 쓰기 캐시 ── [BBU / SuperCap 플래시 백업 모듈]
 └─ 디스크 상태 모니터 & 핫 스페어 제어기
       │ (다채널 SAS / SATA / NVMe 채널)
       ▼
[물리 디스크 어레이 (Physical Disk Array)]
 ├─ 디스크 0 (Data Block 0)
 ├─ 디스크 1 (Data Block 1)
 ├─ 디스크 2 (Data Block 2)
 └─ 디스크 3 (Parity Block P)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; RAID 컨트롤러가 단일 호스트 요청을 분산 물리 드라이브 트랜잭션으로 변환함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **RAID 컨트롤러** | 서버 PCIe 슬롯/메인보드 | 스트라이핑 주소 변환, 패리티 실시간 연산, 디스크 헬스체크 | 하드웨어 전용 ASIC |
| **패리티 가속 엔진**| RAID 컨트롤러 내부 | XOR(RAID 5) 및 리드솔로몬 Galois Field(RAID 6) 가속 | 0 CPU 점유율 패리티 연산 |
| **BBU / SuperCap** | 컨트롤러 장착 모듈 | 정전 시 컨트롤러 DRAM 캐시의 미기록 데이터를 안전 보존 | 쓰기 구멍(Write Hole) 방지 |
| **물리 디스크 어레이**| 서버 드라이브 베이 | 실제 사용자 데이터 및 패리티 블록 분산 저장 | SAS/SATA/NVMe HDD/SSD |

#### 한줄 요약
- RAID 시스템은 컨트롤러(매핑/패리티 엔진), 캐시 및 BBU, 그리고 다채널 물리 디스크 어레이로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기-수정-쓰기(Read-Modify-Write, RMW)**: RAID 5/6에서 전체 스트라이프보다 작은 부분 쓰기 요청 시, 기존 데이터와 기존 패리티를 먼저 읽어 새 패리티를 계산한 후 쓰는 4회 I/O 발생 메커니즘.

</details>

```text
1. 호스트 애플리케이션의 디스크 블록 쓰기 요청
                      │
                      ▼
2. RAID 컨트롤러의 스트라이프 크기 판정
   ┌──────────────────┴──────────────────┐
[ 스트라이프 전체 크기 쓰기 (Full-Stripe) ] [ 부분 쓰기 (Partial-Stripe Write: RMW 발생) ]
   │                                     │
   ▼                                     ▼
3. 새 데이터들로 새 패리티 직접 계산     4. 디스크에서 기존 데이터($D_{old}$)와 기존 패리티($P_{old}$) 읽기 (2 Reads)
   │                                     │
   ▼                                     ▼
5. 데이터와 패리티 동시 기록 (1 Write)    6. $P_{new} = D_{old} \oplus D_{new} \oplus P_{old}$ 계산
   │                                     │
   │                                     ▼
   │                                  7. 새 데이터와 새 패리티를 디스크에 기록 (2 Writes)
   └──────────────────┬──────────────────┘
                      │
                      ▼
8. 호스트에 I/O 쓰기 완료 응답 (부분 쓰기 시 총 4회 I/O 페널티 수반)
```

분기 결과: **전체 스트라이프 쓰기는** 읽기 없이 즉시 끝나나, **부분 쓰기는** RMW로 인해 읽기 2회 + 쓰기 2회(총 4회 I/O)가 발생하여 지연시간이 증가함

#### 한줄 요약
- 전체 쓰기는 패리티를 즉시 계산해 기록하나, 부분 쓰기는 기존 블록을 읽어 새 패리티를 계산하는 RMW 4회 I/O 페널티를 거친다.

## Ⅴ. 종류 및 비교

| RAID 레벨 | 구성 방식 | 최소 디스크 수 | 용량 효율 | 허용 장애 수 | 쓰기 페널티 | 주요 적용처 |
|:---|:---|:---|:---|:---|:---|:---|
| **RAID 0** | 순수 스트라이핑 | 2개 | **100%** | **0개 (1개 고장 시 전체 유실)** | 없음 (최고 속도) | 고속 임시 작업, 영상 렌더링 |
| **RAID 1** | 순수 미러링 (1:1 복제) | 2개 | 50% | 1개 | 없음 (쓰기 2회) | OS 부팅 디스크, 소형 DB |
| **RAID 5** | **단일 분산 패리티 (XOR)** | 3개 | **$(N-1)/N$ (높음)** | **1개 디스크 고장 허용** | **4회 I/O (RMW)** | 범용 파일 서버, 데이터 아카이빙 |
| **RAID 6** | **이중 분산 패리티 (P+Q)** | 4개 | **$(N-2)/N$** | **2개 디스크 동시 고장 허용** | 6회 I/O (이중 RMW) | 대용량 엔터프라이즈 스토리지 |
| **RAID 10**| **미러링 후 스트라이핑 (1+0)** | 4개 (짝수) | 50% | **그룹당 1개 (최대 $N/2$개)** | 없음 (고속 쓰기) | **고성능 트랜잭션 OLTP DB** |

#### 한줄 요약
- 속도와 복구 성능이 최우선이면 RAID 10, 용량 효율과 단일 장애 방어에는 RAID 5, 대용량 이중 장애 방어에는 RAID 6이 선택 기준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핫 스페어(Hot Spare)**: 유휴 대기하다가 어레이 내 특정 디스크 장애 발생 시 즉시 투입되어 자동 재구축(Rebuild)을 시작하는 예비 디스크.
- **패트롤 리드(Patrol Read)**: 백그라운드 유휴 시간에 디스크 전 영역을 정기 검사하여 불량 섹터(URE)를 선제 복구하는 기능.
- **쓰기 구멍(Write Hole)**: RAID 5/6 쓰기 도중 정전 발생 시 데이터와 패리티 간의 정합성이 영구 파괴되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량(10TB+) 디스크 재구축 중 추가 디스크 고장으로 전체 유실 | **RAID 6 또는 RAID 10 구성 및 자동 핫 스페어(Hot Spare)** 연동 | 이중 장애 허용 및 데이터 복구 성공률 100% 보장 |
| 부분 쓰기 도중 불시 정전으로 인한 **쓰기 구멍(Write Hole)** 패리티 왜곡 | **BBU/SuperCap 장착 캐시 및 컨트롤러 저널링(NVRAM)** 적용 | 정전 후 재부팅 시 미완료 쓰기 안전 복구 |
| 장기 미사용 블록의 잠재적 읽기 에러(URE)로 재구축 실패 | **주기적 패트롤 리드(Patrol Read) 및 선제적 섹터 교체** | 배드 섹터 조기 치유 및 재구축 안정성 확보 |

#### 한줄 요약
- 실무에서는 RAID 6/10과 핫 스페어로 이중 장애를 방어하고, BBU 캐시로 쓰기 구멍을 막으며, 패트롤 리드로 URE를 방지한다.

## Ⅶ. 결론

- 엔터프라이즈 스토리지의 성능과 고가용성을 확보하기 위해 **초고속 트랜잭션 DB에는 RAID 10을, 대용량 스토리지 인프라에는 RAID 6을 표준 아키텍처로 채택**하고, 정전 시 데이터 정합성 보장을 위해 **BBU/SuperCap 캐시와 자동 핫 스페어 시스템**을 필수 구축하며, 주기적인 **패트롤 리드(Patrol Read) 예방 정비 체계**를 확립하는 고신뢰 스토리지 시스템 구축

#### 한줄 요약
- RAID는 워크로드 특성에 맞춘 레벨 선택과 BBU, 핫 스페어 및 패트롤 리드의 결합을 통해 무중단 데이터 가용성을 완성한다.
