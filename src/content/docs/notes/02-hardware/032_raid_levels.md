## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RAID(Redundant Array of Independent Disks)**: 복수의 물리 디스크를 논리적인 단일 스토리지 어레이로 묶어 스트라이핑(성능), 미러링(복제), 패리티(오류 복구) 기술을 조합하여 성능 향상과 내고장성을 제공하는 스토리지 가상화 기술.
- **고가용성(High Availability)**: 시스템 구성요소에 단일 물리 장애가 발생하더라도 서비스 중단이나 데이터 손실 없이 정상적인 입출력 운영을 지속할 수 있는 능력.

</details>

- 정의/개념: 복수 드라이브를 논리 어레이로 묶고 분산·복제·잉여 계산을 조합해 성능과 장애 허용성을 조절하는 **RAID**
- 배경/필요성: 단일 드라이브는 대역폭이 한 대에 묶이고 고장 시 곧바로 데이터 접근이 끊겨 **고가용성** 제공할 수 없음

#### 한줄 요약
- RAID가 늘리는 것은 가용성이지 내구성이 아니며, 삭제·손상·재해는 그대로 전파되므로 백업을 대체할 수 없다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 연속된 데이터를 일정 크기의 블록 단위로 분할하여 복수의 물리 디스크에 병렬로 분산 기록함으로써 I/O 대역폭을 극대화하는 기법.
- **미러링(Mirroring)**: 동일한 데이터 블록을 2개 이상의 독립 드라이브에 완전 복제 기록하여 완벽한 데이터 중복성과 무결성을 확보하는 기법.
- **패리티(Parity)**: 데이터 블록들에 대해 비트 단위 XOR 논리 연산을 수행하여 생성한 복구용 잉여 데이터로, 디스크 장애 시 손실된 원본 데이터를 역산 복원하는 기법.

</details>

- **스트라이핑** 기반 다중 드라이브에 I/O를 분산해 순차·병렬 처리량 확대
- **미러링** 기반 동일 데이터 사본을 유지해 드라이브 장애 시 대체 읽기 제공
- **패리티** 기반 데이터 사본보다 적은 중복 용량을 사용해 고장 데이터 재구성

#### 한줄 요약
- **미러링** 용량을 절반 내주고 **패리티** 기반 쓰기 성능을 내주므로, 보호 비용을 공간으로 낼지 시간으로 낼지가 레벨 선택의 본질이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RAID 컨트롤러(RAID Controller)**: 호스트 입출력 요청을 수신하여 스트라이프 주소 매핑, 패리티 연산, 캐시 관리, 디스크 장애 감시를 총괄하는 하드웨어 제어기.
- **배터리 백업 장치(Battery Backup Unit, BBU)**: 정전 등 불시의 전원 차단 시 RAID 컨트롤러의 휘발성 쓰기 캐시 메모리에 보관된 미기록 데이터를 안전하게 유지하는 배터리 전원 모듈.

</details>

```text
[RAID 시스템]
├─ 호스트 인터페이스 (PCIe·SAS)
├─ RAID 컨트롤러
│  ├─ 스트라이프 매퍼 (LBA → 디스크·오프셋)
│  ├─ 패리티 가속 엔진 (XOR·리드솔로몬)
│  └─ 쓰기 캐시
│     └─ BBU (정전 시 캐시 보존)
└─ 물리 디스크 어레이 (디스크 1 ~ N)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 스트라이프 매퍼를 지난 뒤에야 요청이 개별 물리 디스크로 갈라짐

| 구성요소 | 책임 |
|:---|:---|
| **RAID 컨트롤러** | 어레이 상태 감시와 전체 I/O 제어 |
| 스트라이프 매퍼 | 논리 주소를 다중 물리 디스크 번호와 오프셋으로 변환 |
| 패리티 가속 엔진 | XOR 및 리드솔로몬 연산으로 패리티 생성·복구 |
| **BBU** | 정전 시 미완료 쓰기 데이터를 캐시에 보존 |

#### 한줄 요약
- 컨트롤러가 단일 지점에 모든 매핑과 패리티 상태를 쥐고 있으므로, 디스크를 아무리 늘려도 컨트롤러 자체는 여전히 단일 장애점으로 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기-수정-쓰기(Read-Modify-Write, RMW)**: RAID 5/6에서 전체 스트라이프 미만의 부분 쓰기 요청 시, 기존 데이터와 기존 패리티를 먼저 읽어 새 패리티를 계산한 뒤 기록하는 4단계 I/O 오버헤드 메커니즘.

</details>

```text
호스트 쓰기 요청 도달
        │
   스트라이프 전체를 덮는 쓰기인가?
   ┌────┴─────┐
  예           아니오 (부분 쓰기)
   │             │
새 패리티를      기존 데이터·패리티 읽기 (2 Reads)
곧바로 계산       │
   │        P_new = D_old ⊕ D_new ⊕ P_old
   │             │
   │        새 데이터·패리티 쓰기 (2 Writes)
   └────┬────────┘
        │
   호스트에 완료 응답
```

분기 결과: 전체 스트라이프 쓰기는 읽기가 필요 없지만 부분 쓰기는 **RMW** 때문에 디스크 I/O가 4회로 늘어, 같은 데이터양이라도 요청 크기에 따라 비용이 몇 배 갈림

#### 한줄 요약
- 쓰기 페널티는 패리티 계산이 아니라 계산에 필요한 기존 값을 읽어 오는 데서 나오므로, 요청을 스트라이프 크기에 맞추는 것만으로 상당 부분 사라진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RAID 0**: 패리티나 미러링 없이 순수 스트라이핑만 적용하여 100% 용량 효율과 최고 속도를 내지만 장애 허용성이 전혀 없는 구성.
- **RAID 1**: 2개 이상의 디스크에 동일한 데이터를 완전 복제(미러링)하여 단일 디스크 장애를 허용하지만 용량 효율이 50%로 제한되는 구성.
- **RAID 5**: 데이터와 단일 패리티를 모든 디스크에 블록 단위로 분산 기록하여 N-1 용량으로 1개 디스크 장애를 허용하는 구성.
- **RAID 6**: 두 가지 독립된 패리티(P+Q)를 분산 기록하여 N-2 용량으로 2개 디스크의 동시 장애까지 완벽히 허용하는 구성.
- **RAID 10**: 디스크들을 먼저 미러링(RAID 1)으로 묶은 뒤 그 쌍들을 스트라이핑(RAID 0)으로 결합하여 고성능과 고신뢰성을 동시에 구현하는 하이브리드 구성.

</details>

| RAID 레벨 | RAID 0 | RAID 1 | RAID 5 | RAID 6 | RAID 10 |
|:---|:---|:---|:---|:---|:---|
| 적용 기준 | 장애 허용 없이 처리량·용량 우선 | 단순 복구·낮은 읽기 지연 우선 | 단일 장애 허용·용량 효율 우선 | 이중 장애 허용·용량 효율 우선 | 임의 쓰기 성능·복구 속도 우선 |
| 핵심 특징 | 스트라이핑 전용·100% 용량 | 1:1 미러 복제·50% 용량 | 단일 분산 패리티·N-1 용량 | 이중 분산 패리티·N-2 용량 | 미러링 위 스트라이핑 결합 |
| 한계 | 디스크 1개 장애 시 전체 손실 | 저장 효율 50%로 비용 상승 | RMW 오버헤드·재구축 부담 | 2중 패리티 연산 지연 증가 | 고비용·최소 4개 디스크 필요 |

#### 한줄 요약
- 디스크 용량이 커질수록 재구축 시간이 길어져 그동안의 추가 장애 확률이 올라가므로, 대용량 시대에는 RAID 5의 단일 패리티가 사실상 부족해졌다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핫 스페어(Hot Spare)**: 평상시 유휴 상태로 대기하다가 어레이 내 특정 디스크 고장 감지 시 자동으로 활성화되어 즉각 데이터 재구축을 수행하는 예비 디스크.
- **패트롤 리드(Patrol Read)**: 백그라운드 유휴 시간 동안 어레이 내 모든 물리 디스크의 섹터를 주기적으로 전수 검사하여 잠재된 불량 섹터를 선제적으로 검출하고 복구하는 기능.
- **쓰기 구멍(Write Hole)**: RAID 5/6에서 쓰기 도중 정전이나 장애가 발생하여 데이터 블록과 패리티 블록 중 일부만 물리 기록되어 패리티 정합성이 영구 훼손되는 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 드라이브 재구축 중 추가 장애 발생 | **RAID 6** 또는 **RAID 10** 구성에 **핫 스페어** 연동 | 이중 장애 허용 및 재구축 대기 단축 |
| 불시 정전 시 **쓰기 구멍** 기반 데이터·패리티 불일치 | **BBU** 캐시와 저널링 적용 | 미완료 쓰기 복구·패리티 정합성 유지 |
| **RAID 5** 부분 쓰기 집중 시 성능 저하 | 패리티 연산이 없는 RAID 10 구조로 전환 | 쓰기 페널티 제거 및 입출력 지연 안정화 |
| 재구축 중 잠재적 읽기 오류 발생 | 정기적인 **패트롤 리드**·불량 블록 치환 | 배드 섹터 조기 감지·재구축 실패 위험 감소 |

#### 한줄 요약
- 네 대책이 겨누는 것은 장애 자체가 아니라 재구축이라는 취약 구간이며, RAID의 실제 위험은 디스크가 고장 난 순간이 아니라 그 뒤 복구 기간에 있다.

## Ⅶ. 결론

- 임의 쓰기·빠른 재구축은 **RAID 10**, 용량 효율과 이중 장애 허용은 **RAID 6** 선택하되, 장애 도메인·재구축 시간을 검증하고 RAID를 백업 대체 수단으로 사용하지 않음

#### 한줄 요약
- 레벨 선택은 정상 운영 성능이 아니라 한 대가 빠진 상태에서 얼마나 버티고 얼마나 빨리 복구되는지로 판단해야 한다.
