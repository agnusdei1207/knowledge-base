## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RAID(Redundant Array of Independent Disks)**: 복수의 물리 드라이브를 하나의 논리 드라이브로 묶어 스트라이핑, 미러링, 패리티 기법으로 성능과 가용성을 보장하는 스토리지 기술.
- **고가용성(High Availability)**: 디스크 물리적 고장 발생 시에도 서비스 중단이나 데이터 손실 없이 정상 입출력을 유지하는 능력.

</details>

- 정의/개념: 복수의 물리 디스크를 논리 어레이로 묶어 스트라이핑(Striping), 미러링(Mirroring), 패리티(Parity) 기법을 조합함으로써 I/O 성능 및 고가용성을 달성하는 스토리지 가상화 기술
- 배경/필요성: 단일 드라이브의 용량/대역폭 한계를 극복하고, 물리적 디스크 고장에 따른 **데이터 유실 방지 및 무중단 비즈니스 연속성(BCP) 확보**

#### 한줄 요약

- 물리 디스크들을 묶어 **스트라이핑·미러링·패리티**로 성능과 가용성 확보

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 데이터를 블록 단위로 쪼개어 여러 디스크에 동시 분산 기록하여 읽기/쓰기 대역폭을 배가하는 기법.
- **미러링(Mirroring)**: 동일한 데이터를 2개 이상의 디스크에 1:1로 복제하여 100% 내결함성을 제공하는 기법.
- **패리티(Parity)**: XOR 논리 연산 기반의 오류 복구 검사 비트로, 1~2개 드라이브 고장 시 원본 데이터를 역산 복원하는 기술.
- **RMW(Read-Modify-Write)**: 패리티 기반 RAID에서 부분 쓰기 발생 시 기존 데이터/패리티를 읽고 재계산 후 다시 쓰는 4회의 I/O 오버헤드.

</details>

- **스트라이핑(Striping)** 기술을 적용하여 드라이브 개수에 비례하는 병렬 I/O 대역폭 가속 달성
- **미러링** 및 **분산 패리티(XOR)** 보호 기술을 통해 단일/이중 디스크 장애 시 무중단 서비스 및 실시간 복원 제공
- 패리티 갱신 시 발생하는 **RMW(Read-Modify-Write)** 패널티로 인한 랜덤 쓰기 지연시간 증가 수반

#### 한줄 요약

- **스트라이핑 가속**과 **미러링/패리티 내결함성**, RMW 쓰기 패널티 수반

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RAID Controller**: 호스트 인터페이스, XOR 가속 엔진, BBU(배터리 백업) 캐시를 내장하여 어레이를 총괄 제어하는 하드웨어.
- **Stripe Mapper**: 호스트 LBA 논리 주소를 각 물리 디스크 번호와 스트라이프 블록 오프셋으로 변환하는 모듈.

</details>

```text
[ 하드웨어 RAID 컨트롤러 및 스토리지 어레이 구조도 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 시스템 (PCIe / SAS Host Bus Adapter)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 하드웨어 RAID 컨트롤러 (Hardware RAID Controller)            │
│  ├─ 스트라이프 매퍼 (LBA ──> Disk # + Stripe Offset 변환)    │
│  ├─ 하드웨어 XOR / Reed-Solomon 패리티 연산 엔진            │
│  └─ BBU / 플래시 보호 쓰기 캐시 (Write-Back Cache)           │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 물리 드라이브 어레이 (HDD / SSD Drives)                     │
│  [ Disk 0 ]      [ Disk 1 ]      [ Disk 2 ]      [ Disk N ] │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트 버스 인터페이스, RAID 컨트롤러(스트라이프 매퍼/XOR 엔진/BBU 캐시) 및 물리 디스크 배열 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 레이드 컨트롤러 | 논리 어레이의 상태 모니터링, 전체 입출력 흐름 제어 및 디스크 재구축 총괄 |
| 스트라이프 매퍼 | 호스트의 단일 논리 주소를 다중 물리 디스크 번호와 블록 오프셋으로 주소 변환 수행 |
| 배타적 논리합 엔진 | 다중 패리티의 고속 생성 및 데이터 복구를 위한 하드웨어 기반 병렬 논리 연산 가속 |
| 배터리 보호 캐시 (BBU) | 예기치 않은 불시 정전 시 미완료된 쓰기 데이터 및 저널의 안전한 물리적 보존 |

#### 한줄 요약

- **RAID 컨트롤러·스트라이프 매퍼·XOR 가속 엔진·BBU 캐시** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Write Hole**: 패리티 갱신 중 정전 발생 시 데이터와 패리티 간 불일치로 전체 스트라이프 정합성이 파괴되는 결함.

</details>

```text
[ 호스트 부분 블록 쓰기 요청 도달 ]
                 │
                 ▼
[ 1. 기존 데이터(D_old) 및 기존 패리티(P_old) 읽기 (2 Reads) ]
                 │
                 ▼
[ 2. 신규 패리티 연산 : P_new = D_old ⊕ D_new ⊕ P_old (XOR Engine) ]
                 │
                 ▼
[ 3. 신규 데이터(D_new) 및 신규 패리티(P_new) 쓰기 (2 Writes) ]
                 │
                 ▼
[ 4. 총 4회 I/O 완료 후 호스트로 쓰기 완료 응답 반환 ]
```

**동작 원리**

1. **읽기 단계**: 갱신할 위치의 기존 데이터($D_{old}$)와 기존 패리티($P_{old}$)를 디스크에서 읽어옴 (2 Read)
2. **연산 단계**: 하드웨어 XOR 엔진이 $P_{new} = D_{old} \oplus D_{new} \oplus P_{old}$ 연산 수행
3. **쓰기 단계**: 새로운 데이터($D_{new}$)와 계산된 패리티($P_{new}$)를 해당 디스크에 동시 기록 (2 Write)
4. **완료 통보**: 총 4회의 디스크 I/O가 완료되면 호스트로 정상 완료 응답 반환

#### 한줄 요약

- 부분 쓰기 시 **Read(기존 D/P) $\to$ XOR(신규 패리티 연산) $\to$ Write(신규 D/P)** 4회 I/O 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RAID 0 / 1 / 5 / 6 / 10**:
  - RAID 0: 스트라이핑 (성능 최상, 무장애 허용)
  - RAID 1: 미러링 (50% 용량, 1개 장애 허용)
  - RAID 5: 분산 단일 패리티 (1개 장애 허용, 4회 RMW)
  - RAID 6: 분산 이중 패리티 (동시 2개 장애 허용, 6회 RMW)
  - RAID 10: 1+0 미러 스트라이프 (최고 성능/가용성, 50% 용량)

</details>

| RAID 레벨(종류) | 적용 기준 | 핵심 특징 | 제약 사항(한계) |
|:---|:---|:---|:---|
| RAID 0 | 성능 최우선 및 데이터 유실 무관 | 100% 스트라이핑 병렬 입출력 가속 | 단일 디스크 장애 시 전체 데이터 유실 |
| RAID 1 | 운영체제 부팅 및 소규모 핵심 데이터 | 1:1 미러링 기반 100% 데이터 내결함성 | 전체 물리 디스크 용량의 50%만 사용 가능 |
| RAID 5 | 대용량 읽기 중심 스토리지 구성 | 분산 단일 패리티 적용 및 N-1 용량 제공 | 패리티 갱신 오버헤드 및 URE 복구 취약 |
| RAID 6 | 고가용성 대용량 백업 인프라 | 분산 이중 패리티 적용 및 2개 장애 허용 | 6회 입출력 발생으로 쓰기 성능 대폭 저하 |
| RAID 10 | 고성능 무작위 쓰기 트랜잭션 처리 | 미러링 그룹 간 스트라이핑 및 패널티 제거 | 최대 50% 용량 제한 및 고비용 인프라 구축 |

#### 한줄 요약

- 읽기/용량 중심은 **RAID 5/6**, 고성능 OLTP 및 무작위 쓰기는 **RAID 10** 채택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Hot Spare**: 장애 발생 시 컨트롤러가 즉시 예비 드라이브로 승격시켜 자동 재구축(Rebuild)을 시작하는 대기 디스크.
- **Patrol Read**: 유휴 시간에 백그라운드로 전체 디스크를 스캔하여 배드 섹터를 사전에 감지/복구하는 예방 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 디스크 **재구축** 중 추가적인 디스크 장애 발생 시 어레이 전체 붕괴 | 다중 장애를 견디는 **레이드 6** 적용 및 시스템 내 **핫 스페어** 연동 구축 | 2개의 동시 물리적 장애 발생 시에도 완벽 복원 및 고가용성 보장 |
| 불시 정전 발생 시 쓰기 구멍 현상으로 인한 복구 불가 정합성 파괴 | 하드웨어 컨트롤러 내부에 전용 배터리 보호 캐시 및 쓰기 저널 메모리 장착 | 정전 발생에도 미완료 쓰기 작업 원자적 복구 보장 |
| 대량의 무작위 쓰기 워크로드 집중 시 읽기 수정 쓰기 지연시간 대폭 폭증 | 패리티 갱신이 없는 직관적인 **레이드 10** 구조로 인프라 아키텍처 전환 적용 | 복잡한 패리티 연산 패널티 완전 제거 및 입출력 지연 안정화 |
| 장시간 재구축 도중 배드 섹터 발견으로 인한 읽기 복구 실패 발생 | 유휴 시간에 백그라운드에서 저부하 **순찰 읽기** 예약 작업 주기적 수행 | 배드 섹터 사전 감지 및 투명한 예비 섹터 치환으로 복구 신뢰성 확보 |

#### 한줄 요약

- 이중 패리티가 필요하면 RAID 6이나 10으로 전환하고, Hot Spare 자동 승격으로 디스크 장애에 즉시 대응하며, BBU 캐시로 Write Hole을 방어하고, Patrol Read로 잠복 불량을 사전 탐지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **대용량 HDD 환경의 URE(Unrecoverable Read Error)**: 10TB+ 고용량 드라이브 재구축 시 비트 에러 발생 확률이 급증하므로 RAID 5는 지양하고 RAID 6 또는 RAID 10 사용이 필수적.

</details>

- **엔터프라이즈 스토리지 설계 시**: 무작위 쓰기 워크로드는 RAID 10, 읽기/용량 중심은 RAID 6 표준 채택

#### 한줄 요약

- **용량 효율성, 쓰기 패널티(RMW), 재구축 시간(URE)**에 맞춘 최적 RAID 레벨 선정
