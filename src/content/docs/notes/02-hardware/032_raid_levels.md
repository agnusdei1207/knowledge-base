## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **복수 배열 독립 디스크(Redundant Array of Independent Disks)**: 복수의 물리 디스크를 논리적으로 묶어 스트라이핑, 미러링, 패리티 기법으로 성능과 가용성을 보장하는 스토리지 아키텍처이다.
- **가용성(Availability)**: 어레이 내부 디스크가 물리적으로 고장 나더라도 서비스 정지나 데이터 유실 없이 정상적인 접근성을 지속해서 유지하는 시스템 안정성이다.

</details>

- 정의: 복수의 물리 디스크를 논리 어레이로 구성하여 데이터 스트라이핑, 미러링 및 패리티 기술로 고성능과 고가용성을 동시에 구현하는 스토리지 아키텍처
- 배경: 단일 디스크의 입출력 성능 한계를 극복하고 하드웨어 물리적 고장에 따른 치명적인 데이터 유실을 원천적으로 방지하기 위함

#### 한줄 요약

- 여러 개의 디스크를 묶어 데이터를 분산시키고 복제하며 수학적 검사값을 활용하여 성능과 장애 복구력을 극대화하는 저장소 설계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 데이터를 여러 블록으로 잘라 여러 디스크에 분산 적재함으로써 다중 디스크가 동시에 작업하게 하여 대역폭을 가속하는 기법이다.
- **미러링(Mirroring)**: 동일한 데이터를 2개 이상의 디스크에 똑같이 1대 1로 복제하여 하나의 디스크가 고장 나도 즉각 복구를 지원하는 기법이다.
- **패리티(Parity)**: 디스크 고장 시 잃어버린 데이터를 나머지 디스크들의 데이터를 활용해 배타적 논리합(XOR) 역산으로 복원해 내는 검사 데이터이다.
- **읽기 수정 쓰기(Read-Modify-Write)**: 패리티 기반 어레이에서 작은 단위의 갱신이 발생할 때 기존 데이터를 읽어와서 계산한 후 다시 써야 하므로 발생하는 4회의 입출력 지연 현상이다.

</details>

- **스트라이핑** 기술을 적용하여 장착된 물리 디스크 개수에 정비례하는 병렬 입출력 가속을 달성함.
- **미러링** 및 **패리티** 보호 기술을 통하여 물리적 디스크 장애 시에도 무중단 서비스 및 실시간 데이터 복원을 제공함.
- 패리티 갱신 시 필연적인 **읽기 수정 쓰기** 패널티로 인하여 쓰기 입출력 지연이 구조적으로 발생함.

#### 한줄 요약

- 속도를 높이는 분산 적재, 안정성을 높이는 복제 및 검사 기술을 조합하여 워크로드에 맞는 효율성과 가용성의 타협점을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레이드 컨트롤러(RAID Controller)**: 스트라이핑 매핑, 패리티 연산, 재구축 등 어레이의 모든 두뇌 역할을 통제하는 전용 하드웨어 반도체이다.
- **스트라이프 매퍼(Stripe Mapper)**: 호스트의 논리 주소를 각 물리 디스크 번호와 블록 오프셋으로 매핑하는 주소 변환 엔진이다.
- **배타적 논리합 엔진(XOR Engine)**: 패리티 생성 및 디스크 장애 시 역연산을 통한 데이터 복구를 하드웨어적으로 가속하는 전용 연산 유닛이다.

</details>

```text
[ 하드웨어 레이드 컨트롤러 아키텍처 ]
+-------------------------------------------------------------+
| 호스트 버스 인터페이스 (컴퓨터와 컨트롤러 간 통신)          |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 하드웨어 레이드 컨트롤러                                    |
|  ├─ 스트라이프 매퍼 (논리 주소 물리 분산 매핑)              |
|  ├─ 배타적 논리합 엔진 (패리티 고속 계산 및 복구)           |
|  └─ 배터리 보호 캐시 (정전 대비 고속 쓰기 버퍼)             |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 물리 디스크 배열                                            |
|  [ 디스크 0 ]  [ 디스크 1 ]  [ 디스크 2 ]  [ 디스크 N ]     |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **레이드 컨트롤러** | 논리 어레이의 상태 모니터링, 전체 입출력 흐름 제어 및 디스크 재구축 총괄 |
| **스트라이프 매퍼** | 호스트의 단일 논리 주소를 다중 물리 디스크 번호와 블록 오프셋으로 주소 변환 수행 |
| **배타적 논리합 엔진** | 다중 패리티의 고속 생성 및 데이터 복구를 위한 하드웨어 기반 병렬 논리 연산 가속 |
| 배터리 보호 캐시 | 예기치 않은 불시 정전 시 미완료된 쓰기 데이터 및 저널의 안전한 물리적 보존 |

#### 한줄 요약

- 전용 컨트롤러가 주소를 분산하고 패리티를 연산하며, 배터리로 캐시를 보호하여 다중 물리 디스크를 단일 안전 장치로 격상시킨다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **부분 스트라이프 쓰기(Partial Stripe Write)**: 전체 스트라이프 너비보다 작은 단위의 부분적 갱신으로 패리티 재계산을 위한 읽기 수정 쓰기 지연을 유발하는 현상이다.
- **쓰기 구멍(Write Hole)**: 부분 쓰기 중 불시 정전이 발생하여 데이터는 갱신되었으나 패리티는 갱신되지 못해 어레이 전체의 정합성이 파괴되는 결함 현상이다.

</details>

```text
[ 레이드 5 읽기 수정 쓰기 기반 부분 스트라이프 쓰기 흐름 ]
                      │
                      ▼
     [ 1. 호스트 부분 쓰기 요청 도달 ]
                      │
                      ▼
 [ 2. 갱신 위치의 기존 데이터 및 기존 패리티 읽기 ]
                      │
                      ▼
       [ 3. 배타적 논리합 엔진 신규 패리티 계산 ]
                      │
                      ▼
  [ 4. 신규 데이터 및 신규 패리티 덮어쓰기 완료 ]
                      │
                      ▼
        [ 5. 호스트로 쓰기 완료 응답 반환 ]
```

### 동작 원리

1. 쓰기 요청: 호스트가 갱신할 **부분 스트라이프 쓰기**의 데이터와 블록을 식별함.
2. 데이터 및 패리티 읽기: 부분 갱신을 위해 기존 데이터와 기존 패리티를 디스크에서 읽어옴.
3. 신규 패리티 계산: 기존 값들과 신규 입력 값을 이용하여 **배타적 논리합 엔진**이 패리티를 역산출함.
4. 신규 데이터 및 패리티 기록: 계산된 새 패리티와 데이터를 **쓰기 구멍** 결함 없이 안전하게 디스크에 기록함.
5. 쓰기 완료 반환: 디스크 영속성 조건을 모두 만족한 후 호스트에 완료 응답을 반환함.

#### 한줄 요약

- 패리티를 갱신하기 위해 기존 데이터들을 읽어오고 재계산한 후 다시 디스크에 쓰는 총 4번의 번거로운 과정을 필수적으로 거친다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **레이드 0(RAID 0)**: 분산 적재를 통해 성능을 극대화하나 하나의 디스크 고장에도 전체가 파괴되는 가용성 미지원 레벨이다.
- **레이드 1(RAID 1)**: 거울처럼 똑같이 1대 1로 복제하여 디스크 한 개 고장을 즉시 방어하나 용량 효율이 50%에 불과한 레벨이다.
- **레이드 5(RAID 5)**: 분산 패리티를 사용하여 1개 디스크 분량의 용량만 희생하고 1개의 디스크 장애를 허용하는 효율적인 레벨이다.
- **레이드 6(RAID 6)**: 이중 패리티를 사용하여 2개 디스크 분량의 용량을 희생하고 2개의 동시 디스크 장애를 허용하는 고신뢰성 레벨이다.
- **레이드 10(RAID 10)**: 미러링을 먼저 구성하고 그것을 다시 스트라이핑으로 묶어 고성능과 고가용성을 모두 잡은 프리미엄 레벨이다.

</details>

| 비교 항목 | 레이드 0 | 레이드 1 | 레이드 5 | 레이드 6 | 레이드 10 |
|:---|:---|:---|:---|:---|:---|
| 기본 메커니즘 구성 | **스트라이핑** | **미러링** | 분산 단일 패리티 | 분산 이중 패리티 | 미러링 후 스트라이핑 |
| 실효 용량 효율성 | 100% 효율 달성 | 50% 절반 효율 | (N-1)/N 효율 | (N-2)/N 효율 | 50% 절반 효율 |
| 어레이 허용 고장 수 | 허용 불가 파괴 | 1개 디스크 허용 | 1개 디스크 허용 | 최대 2개 동시 허용 | 거울 쌍마다 1개 허용 |
| 갱신 쓰기 패널티 | 패널티 전혀 없음 | 1회 단순 추가 쓰기 | 최소 4회 복합 입출력 | 최소 6회 복합 입출력 | 다중 복제 단순 쓰기 |
| 적용 대상 시스템 | 임시 고속 작업 인프라 | 운영체제 부팅 디스크 | 대용량 웹 및 일반 데베 | 고가용 대용량 백업 망 | 초고속 온라인 트랜잭션 |

#### 한줄 요약

- 용량과 가성비가 핵심이면 5와 6을 사용하고, 데이터 유실이 절대 용납되지 않는 최고속 데이터베이스는 10을 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핫 스페어(Hot Spare)**: 평소에는 대기하다가 장애 발생 시 즉각 컨트롤러에 의해 자동 승격되어 복구용으로 투입되는 예비용 디스크이다.
- **재구축(Rebuild)**: 장애 디스크 교체 후 나머지 정상 디스크들의 데이터를 모두 읽어와 새 디스크에 원래 데이터를 재생성하는 막대한 부하 작업이다.
- **순찰 읽기(Patrol Read)**: 디스크가 한가한 유휴 시간 중에 백그라운드에서 전체 섹터를 읽어 배드 섹터를 사전 감지하고 치환하는 선제적 관리 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 디스크 **재구축** 중 추가적인 디스크 장애 발생 시 어레이 전체 붕괴 | 다중 장애를 견디는 **레이드 6** 도입 및 시스템 내 **핫 스페어** 연동 구축 | 2개의 동시 물리적 장애 발생 시에도 완벽 복원 및 고가용성 보장 |
| 불시 정전 발생 시 쓰기 구멍 현상으로 인한 복구 불가 정합성 파괴 | 하드웨어 컨트롤러 내부에 전용 배터리 보호 캐시 및 쓰기 저널 메모리 장착 | 정전 발생에도 미완료 찌꺼기 쓰기 작업 원자적 100% 복구 보장 |
| 대량의 무작위 쓰기 워크로드 집중 시 읽기 수정 쓰기 지연시간 대폭 폭증 | 패리티 갱신이 없는 직관적인 **레이드 10** 구조로 인프라 아키텍처 전환 적용 | 복잡한 패리티 연산 패널티 완전 제거 및 입출력 지연 극적 안정화 |
| 장시간 재구축 도중 배드 섹터 발견으로 인한 치명적인 읽기 복구 실패 발생 | 유휴 시간에 백그라운드에서 저부하 **순찰 읽기** 예약 작업 주기적 수행 | 배드 섹터 사전 감지 및 투명한 예비 섹터 치환으로 복구 신뢰성 확보 |

#### 한줄 요약

- 다중 장애 대비로 레이드 6과 예비 디스크를 결합하고 순찰 읽기로 배드 섹터를 선제 타격하며 배터리 캐시로 쓰기 구멍을 막아낸다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **아키텍처 선택 기준(Architecture Decision Criteria)**: 대상 시스템의 무작위 쓰기 비율, 허용 고장 수 목표, 디스크 단일 용량 및 비용 효율성을 종합 평가하여 최적 레벨을 확정하는 결정 프레임워크이다.

</details>

- 무작위 쓰기 성능과 초저지연이 우선이면 **레이드 10**, 방대한 용량 대비 다중 장애 허용이 우선이면 **레이드 6**을 선택함

#### 한줄 요약

- 데이터의 가치와 입출력 패턴, 그리고 복구에 걸리는 시간을 계산하여 용량 효율과 안정성 사이에서 최적의 레벨을 조율해야 한다.
