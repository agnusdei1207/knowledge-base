## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RAID(Redundant Array of Independent Disks)**: 복수 드라이브를 논리 어레이로 묶어 스트라이핑·미러링·패리티로 성능과 장애 허용성을 조정하는 스토리지 기술.
- **고가용성(High Availability)**: 시스템 물리적 고장 발생 시에도 서비스 중단이나 데이터 유실 없이 정상 입출력을 유지하는 능력.

</details>

- 정의/개념: 복수의 물리 드라이브를 단일 논리 드라이브로 구성하여 **스트라이핑·미러링·패리티**로 가용성을 높이는 저장 제어 기술
- 배경/필요성: 단일 디스크의 물리적 I/O 대역폭 한계 및 하드웨어 고장 시 발생하는 **데이터 영구 소실 위험**

#### 한줄 요약
- 여러 디스크를 하나처럼 묶어 성능을 높이거나, 복사본과 패리티를 두어 고장에 대비하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 데이터를 여러 디스크에 블록 단위로 분산 기록해 I/O 대역폭을 높이는 방식.
- **미러링(Mirroring)**: 동일한 데이터를 두 개 이상의 드라이브에 완전 복제해 무결성을 유지하는 기법.
- **패리티(Parity)**: XOR 연산으로 에러 검출·복구용 잉여 데이터를 생성해 저장 공간 효율을 높이는 방식.

</details>

- **스트라이핑**을 통한 다중 드라이브 병렬 입출력으로 입출력 대역폭 극대화
- **미러링**을 통한 1:1 데이터 복제로 무결성 및 장애 허용성 보장
- **패리티(Parity)** 연산으로 디스크 1~2개 고장 시 데이터 실시간 복구

#### 한줄 요약
- 스트라이핑으로 속도를 올리고, 미러링과 패리티로 디스크 고장 시 데이터 손실을 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RAID 컨트롤러(RAID Controller)**: 호스트 입출력 요청을 받아 스트라이프 매핑 및 패리티 연산을 총괄하는 제어기.
- **BBU(Battery Backup Unit)**: 정전 시 컨트롤러 캐시 데이터를 보존하는 배터리 백업 장치.

</details>

```text
[ 호스트 인터페이스 (PCIe / SAS) ]
                │
                ▼
┌───────────────────────────────────────────────┐
│ RAID 컨트롤러 (H/W Controller)                 │
│  ├─ 스트라이프 매퍼 (LBA → 디스크 어레이 매핑)│
│  ├─ XOR / Reed-Solomon 패리티 가속 엔진       │
│  └─ BBU 지원 비휘발성 쓰기 캐시               │
└───────────────────────┬───────────────────────┘
                        │
      ┌─────────────────┼─────────────────┐
      ▼                 ▼                 ▼
 [ 물리 디스크 1 ] [ 물리 디스크 2 ] [ 물리 디스크 N ]
```

선의 의미: 가지(`├─`)는 컨트롤러 내부 엔진 소유; 하단 화살표는 각 물리 디스크로의 I/O 분산 경로

| 구성요소 | 책임 |
|:---|:---|
| RAID 컨트롤러 | 어레이 상태 감시 및 전체 I/O 제어 |
| 스트라이프 매퍼 | 논리 주소를 다중 물리 디스크 번호와 오프셋으로 변환 |
| 패리티 가속 엔진 | XOR 및 리드솔로몬 연산으로 패리티 생성·복구 |
| BBU 보호 캐시 | 정전 시 미완료 쓰기 데이터의 안전한 보존 |

#### 한줄 요약
- 컨트롤러가 주소를 나누고 패리티를 계산하며, 캐시 전력을 보호해 무결성을 지킨다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RMW(Read-Modify-Write)**: RAID 5/6에서 부분 쓰기 시 기존 데이터와 패리티를 읽고 새 패리티를 계산해 쓰는 과정.

</details>

```text
호스트 부분 블록 쓰기 요청
      │
      ▼
1. 기존 데이터 및 패리티 읽기 (2 Reads)
      │
      ▼
2. 신규 패리티 계산 (P_new = D_old ⊕ D_new ⊕ P_old)
      │
      ▼
3. 신규 데이터 및 패리티 쓰기 (2 Writes)
      │
      ▼
4. I/O 완료 통보 및 호스트 응답 반환
```

**동작 원리**

1. **기존 데이터 및 패리티 읽기**: 갱신 위치의 기존 데이터와 패리티를 인출
2. **신규 패리티 계산**: XOR 하드웨어 엔진으로 신규 패리티 산출
3. **신규 데이터 및 패리티 쓰기**: 새 데이터와 패리티를 해당 디스크에 동시 기록
4. **I/O 완료 통보 및 호스트 응답 반환**: 4회 디스크 I/O 완료 후 정상 응답 반환

#### 한줄 요약
- RAID 5 부분 쓰기는 읽기 2회, 계산 1회, 쓰기 2회로 총 4회의 디스크 I/O가 발생한다.

## Ⅴ. 종류 및 비교

| RAID 레벨 | RAID 0 | RAID 1 | RAID 5 | RAID 6 | RAID 10 |
|:---|:---|:---|:---|:---|:---|
| 적용 기준 | 성능 최우선·데이터 무손실 무관 | OS 부팅·소규모 핵심 DB | 읽기 중심 대용량 스토리지 | 고가용성 대용량 아카이브 | 고성능 임의 쓰기 트랜잭션 |
| 핵심 특징 | 스트라이핑 전용·100% 용량 | 1:1 미러 복제·50% 용량 | 단일 분산 패리티·N-1 용량 | 이중 분산 패리티·N-2 용량 | 미러링 위 스트라이핑 결합 |
| 한계 | 디스크 1개 장애 시 전체 손실 | 저장 효율 50%로 비용 상승 | RMW 오버헤드·재구축 부담 | 2중 패리티 연산 지연 증가 | 고비용·최소 4개 디스크 필요 |

#### 한줄 요약
- 성능만 원하면 0, 안전한 복제는 1, 용량과 보호 절충은 5/6, 고성능과 안전 결합은 10을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핫 스페어(Hot Spare)**: 디스크 장애 시 자동으로 투입되어 즉시 재구축을 시작하는 대기 드라이브.
- **패트롤 리드(Patrol Read)**: 유휴 시간에 전체 디스크를 주기적으로 검사해 잠재적 배드 섹터를 예방 복구하는 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 드라이브 재구축 중 추가 장애 발생 | **RAID 6** 또는 RAID 10 구성 및 **핫 스페어** 연동 | 이중 장애 허용 및 재구축 대기 단축 |
| 불시 정전 시 **Write Hole** 데이터 불일치 | **BBU 보호 캐시** 및 저널링 스토리지 적용 | 정전 발생 시 데이터 정합성 유지 |
| RAID 5 부분 쓰기 집중 시 성능 저하 | 패리티 연산 없는 **RAID 10** 구조 전환 | 쓰기 페널티 제거 및 입출력 지연 안정화 |
| 재구축 중 잠재적 읽기 에러(URE) 발생 | 정기적인 **패트롤 리드** 및 사전 블록 치환 | 배드 섹터 조기 감지 및 복구 신뢰성 확보 |

#### 한줄 요약
- 핫 스페어로 복구 시간을 줄이고, BBU 캐시로 정전을 방어하며, 패트롤 리드로 잠재 불량을 예방한다.

## Ⅶ. 결론

- 무작위 쓰기와 저지연은 **RAID 10**, 용량 효율과 안정성은 **RAID 6** 선택

#### 한줄 요약
- 가용성과 쓰기 패턴, 디스크 재구축 시간을 종합적으로 고려해 최적의 RAID 레벨을 구성해야 한다.
