## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **RAID(Redundant Array of Independent Disks)**: 복수의 물리 드라이브를 단일 논리 스토리지 어레이로 결합하고 스트라이핑(성능), 미러링(복제), 패리티(오류 복구) 기술을 조합하여 고속 I/O 대역폭과 내고장성을 제공하는 스토리지 가상화 기술.
- **고가용성(High Availability)**: 단일 디스크의 물리적 파손이 발생하더라도 시스템 중단 없이 정상적인 읽기/쓰기 서비스를 지속할 수 있는 신뢰성 능력.

</details>

- 정의/개념: 복수의 물리 드라이브를 단일 논리 볼륨으로 묶고 **스트라이핑, 미러링, 패리티 연산**을 조합하여 고속 대역폭과 무중단 내고장성을 제공하는 **스토리지 가상화 아키텍처**
- 배경/필요성: 단일 디스크 드라이브의 I/O 대역폭 병목 해소 및 물리 장애 발생 시 데이터 유실 차단과 서비스 연속성 확보

#### 한줄 요약
- RAID는 여러 디스크를 하나로 묶어 스트라이핑으로 속도를 높이고 미러링/패리티로 장애를 방어하는 스토리지 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스트라이핑(Striping)**: 데이터를 고정 크기 블록 단위로 쪼개어 복수의 디스크에 병렬로 분산 기록함으로써 총 I/O 대역폭을 극대화하는 기법.
- **미러링(Mirroring)**: 동일한 데이터 블록을 2개 이상의 독립 디스크에 1:1 완전 복제하여 완벽한 데이터 중복성을 확보하는 기법.
- **패리티(Parity)**: 데이터 블록 간 XOR 논리 연산을 통해 생성한 복구용 잉여 데이터로, 디스크 1~2개 고장 시 손실된 원본을 수학적으로 복원하는 기법.

</details>

- **스트라이핑 분산 저장**을 통해 복수 디스크 채널에 블록을 병렬 기록함으로써 순차 및 임의 I/O 대역폭 극대화
- **미러링 및 패리티 연산(XOR/Reed-Solomon)**을 적용하여 단일 또는 복수 디스크 장애 시에도 무중단 실시간 복구 지원
- 복구 신뢰성을 확보하는 대가로 부분 쓰기 시 **읽기-수정-쓰기(RMW) 쓰기 페널티** 및 패리티 저장 공간 소모 수반

#### 한줄 요약
- 스트라이핑은 성능을, 미러링과 패리티는 안정성을 제공하며, 용량 효율과 쓰기 속도 간의 상충 관계를 갖는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **RAID 컨트롤러(RAID Controller / HBA)**: 호스트 입출력 요청을 받아 LBA 스트라이프 매핑, 패리티 연산, 쓰기 캐시 관리, 디스크 장애 감시를 전담하는 하드웨어 ASIC.
- **배터리 백업 장치(Battery Backup Unit, BBU / SuperCap)**: 정전 시 컨트롤러의 휘발성 DRAM 쓰기 캐시에 잔류한 데이터를 비휘발성 플래시로 안전하게 덤프할 수 있도록 전력을 공급하는 모듈.

</details>

```text
+-------------------------------------------------------------+
|              호스트 서버 (Host OS & 파일 시스템)            |
+-------------------------------------------------------------+
                               | PCIe / SAS / NVMe 버스 명령
                               v
+-------------------------------------------------------------+
|               하드웨어 RAID 컨트롤러 (RAID ASIC)            |
|  +-------------------------------------------------------+  |
|  | 스트라이프 주소 변환 매퍼 (LBA -> 채널/디스크 오프셋) |  |
|  +-------------------------------------------------------+  |
|  | 하드웨어 패리티 엔진 (XOR / Reed-Solomon 복구 가속기) |  |
|  +-------------------------------------------------------+  |
|  | DRAM 쓰기 캐시 버퍼  <--->  BBU / SuperCap 백업 플래시|  |
|  +-------------------------------------------------------+  |
|  | 디스크 상태 모니터링 & 핫 스페어(Hot Spare) 자동 절체 |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
                               | SAS / SATA / NVMe 다중 채널
                               v
+-------------------------------------------------------------+
|               물리 디스크 드라이브 어레이                   |
|  +-----------+  +-----------+  +-----------+  +-----------+  |
|  | 디스크 0  |  | 디스크 1  |  | 디스크 2  |  | 디스크 3  |  |
|  | [블록 D0] |  | [블록 D1] |  | [블록 D2] |  | [패리티 P]|  |
|  +-----------+  +-----------+  +-----------+  +-----------+  |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표는 호스트 I/O 요청이 RAID 컨트롤러에서 스트라이핑 및 패리티 연산을 거쳐 복수의 물리 디스크 드라이브로 병렬 분산 전달되는 데이터 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| RAID 컨트롤러 | 논리 LBA를 디스크별 물리 블록으로 매핑하고 **스트라이핑 스케줄링 총괄** |
| 패리티 가속 엔진 | XOR 및 리드솔로몬 연산을 전담하여 **CPU 부하 없는 초고속 패리티 계산** |
| DRAM 캐시 및 BBU | 고속 쓰기 버퍼링을 제공하고 정전 시 캐시를 보존하여 **쓰기 구멍 방지** |
| 물리 디스크 어레이 | 스트라이프 단위 데이터 블록과 복구용 패리티를 **분산 영구 보관** |

#### 한줄 요약
- RAID 컨트롤러가 호스트와 디스크 사이에 끼어들어 여러 물리 디스크를 단일 볼륨으로 감추고, 매 쓰기마다 발생하는 XOR 연산은 전용 패리티 엔진이 호스트 CPU를 대신해 떠맡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기-수정-쓰기(Read-Modify-Write, RMW)**: RAID 5/6에서 전체 스트라이프보다 작은 부분 쓰기 요청 시, 기존 데이터와 기존 패리티를 먼저 읽어 새 패리티를 계산한 후 쓰는 4회 I/O 발생 메커니즘.

</details>

```text
+-------------------------------------------------------------+
|               호스트의 디스크 블록 쓰기 요청 도착            |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     1. 스트라이프 크기 판정   |
               +-------------------------------+
                      |                 |
            [풀 스트라이프 쓰기]        | [부분 스트라이프 쓰기]
                      |                 v
                      | +-------------------------------+
                      | | 2. 기존 데이터 및 패리티 판독 |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 3. 새 패리티 XOR 재계산       |
                      | +-------------------------------+
                      |                 |
                      |                 v
                      | +-------------------------------+
                      | | 4. 새 데이터 및 패리티 기록   |
                      | |    (총 4회 I/O RMW 페널티)    |
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 데이터·패리티 동시 기록|               |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
|       5. 디스크 기록 완료 및 호스트 I/O 응답 반환 완료       |
+-------------------------------------------------------------+
```

분기 결과: **풀 스트라이프 쓰기**는 기존 판독 없이 새 패리티를 즉시 계산하여 단 1회 쓰기로 끝나나, **부분 쓰기**는 이전 데이터와 패리티를 읽고 재계산하는 4회 I/O(RMW) 페널티가 발생함

**동작 원리**

1. **스트라이프 쓰기 크기 판정**: RAID 컨트롤러가 호스트 쓰기 요청 크기를 분석하여 스트라이프 전폭(Full-Stripe) 쓰기인지 부분(Partial) 쓰기인지 판별
2. **기존 데이터 및 패리티 판독**: 부분 쓰기인 경우 변경 대상 디스크의 기존 데이터 블록과 기존 패리티 블록을 디스크에서 선행 인출
3. **새 패리티 실시간 연산**: 하드웨어 XOR 엔진이 $P_{new} = D_{old} \oplus D_{new} \oplus P_{old}$ 공식을 적용하여 새 패리티 블록 고속 산출
4. **새 데이터 및 패리티 분산 기록**: 계산 완료된 새 데이터 블록과 새 패리티 블록을 해당 물리 디스크에 각각 병렬 기록(총 4회 I/O)
5. **트랜잭션 완료 및 응답 반환**: 모든 대상 디스크의 기록 완료 신호를 확인하고 호스트 OS 파일 시스템으로 쓰기 성공 응답 최종 통지

#### 한줄 요약
- 전체 쓰기는 패리티를 즉시 계산해 기록하나, 부분 쓰기는 기존 블록을 읽어 새 패리티를 계산하는 RMW 4회 I/O 페널티를 거친다.

## Ⅴ. 종류 및 비교

| RAID 레벨 | RAID 0 | RAID 1 | RAID 5 | RAID 6 | RAID 10 |
|:---|:---|:---|:---|:---|:---|
| 적용 기준 | 무결함 비요구 고속 임시 작업 및 스크래치 볼륨 | 고신뢰 OS 부팅 디스크 및 소형 고가용성 환경 | 비용 절감과 읽기 중심 범용 파일 서버 | 대용량 엔터프라이즈 스토리지 및 콜드 아카이브 | 초고성능 미션 크리티컬 OLTP 및 고속 DB |
| 핵심 특징 | 순수 **스트라이핑** 기반 100% 용량 효율 및 병렬 대역폭 극대화 | 순수 **미러링** (1:1 복제) 기반 단순 복제 및 단일 장애 허용 | 단일 **분산 패리티** (XOR) 기반 $(N-1)/N$ 효율 및 1개 장애 허용 | 이중 **분산 패리티** (P+Q) 기반 $(N-2)/N$ 효율 및 2개 장애 허용 | **미러링 후 스트라이핑** (1+0) 결합 및 그룹당 1개 복수 장애 허용 |
| 한계 | 내고장성 완전 부재로 단 1개 드라이브 장애 시 전체 전손 | 50%의 낮은 저장 공간 효율 및 디스크 증설 원가 상승 | 부분 쓰기 시 4회 I/O (**RMW 페널티**) 및 재구축 중 취약 | 부분 쓰기 시 6회 I/O (이중 RMW) 및 복구 연산 부하 | 50%의 용량 효율로 인한 스토리지 구축 비용 상승 |

#### 한줄 요약
- 속도와 복구 성능이 최우선이면 RAID 10, 용량 효율과 단일 장애 방어에는 RAID 5, 대용량 이중 장애 방어에는 RAID 6이 선택 기준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **핫 스페어(Hot Spare)**: 유휴 대기하다가 어레이 내 특정 디스크 장애 발생 시 즉시 투입되어 자동 재구축(Rebuild)을 시작하는 예비 디스크.
- **패트롤 리드(Patrol Read)**: 백그라운드 유휴 시간에 디스크 전 영역을 정기 검사하여 불량 섹터(URE)를 선제 복구하는 기능.
- **쓰기 구멍(Write Hole)**: RAID 5/6 쓰기 도중 정전 발생 시 데이터와 패리티 간의 정합성이 영구 파괴되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 디스크 재구축 중 추가 장애로 인한 어레이 파괴 | **RAID 6 도입** 및 핫 스페어 자동 절체 연동 | 2개 동시 장애 허용 및 복구 성공률 극대화 |
| 부분 쓰기 도중 정전 발생 시 데이터-패리티 불일치 | **BBU/SuperCap 캐시** 및 플래시 덤프 적용 | **쓰기 구멍** 방지 및 캐시 데이터 무결성 보장 |
| 잠재적 읽기 에러(URE)로 인한 재구축 실패 | 주기적 **패트롤 리드** 선제 검사 및 교체 | 배드 섹터 조기 치유 및 백그라운드 무결성 유지 |

#### 한줄 요약
- 실무에서는 RAID 6/10과 핫 스페어로 이중 장애를 방어하고, BBU 캐시로 쓰기 구멍을 막으며, 패트롤 리드로 URE를 방지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **소프트웨어 정의 스토리지(Software-Defined Storage, SDS)**: 하드웨어 RAID 카드 대신 Ceph, ZFS 등의 소프트웨어 계층에서 분산 소거 코딩(Erasure Coding)을 수행하는 차세대 아키텍처.
- **소거 코딩(Erasure Coding)**: 데이터를 $k$개 데이터 청크와 $m$개 패리티 청크로 분할 인코딩하여 대규모 분산 환경에서 임의의 $m$개 노드 장애를 허용하는 수학적 내고장성 기법.

</details>

스트라이핑과 패리티 연산의 조합을 통해 단일 드라이브 한계를 극복하는 스토리지 핵심 기술이며, 클라우드 환경에서 소프트웨어 정의 스토리지(SDS) 및 분산 소거 코딩(Erasure Coding)으로의 구조적 확장.

#### 한줄 요약
- RAID는 워크로드 특성에 맞춘 레벨 선택과 BBU, 핫 스페어 및 패트롤 리드의 결합을 통해 무중단 데이터 가용성을 완성한다.
