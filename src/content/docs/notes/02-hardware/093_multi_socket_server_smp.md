## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티소켓 서버(Multi-Socket Server)**: 메인보드 한 장에 CPU 칩을 2개 이상 꽂아 놓고, 메모리를 수 테라바이트로 뻥튀기하는 거대한 괴물 서버이다.
- **대칭형 다중 처리(Symmetric Multiprocessing, SMP)**: 수십 개의 코어와 메모리 구역이 찢어져 있어도, 프로그램한테는 통짜 컴퓨터 한 대인 것처럼 사기 쳐서 돌리는 아키텍처이다.
- **캐시 일관성 불균일 메모리 접근(Cache-Coherent Non-Uniform Memory Access, ccNUMA)**: 자기 구역 램을 쓸 때랑 남의 구역 램을 쓸 때 속도 차이는 나지만, 데이터 꼬이는 건 절대 막아주는 깐깐한 동기화 시스템이다.

</details>

- 정의: 메인보드 한 장에 CPU 칩을 2개 이상 꽂아 놓고, 메모리를 대칭적으로 하나처럼 엮어 쓰는 거대한 괴물 아키텍처인 **멀티소켓 서버 & 대칭형 다중 처리(SMP)**
- 배경: 칩 하나에 들어가는 코어 수와 꽂을 수 있는 램 슬롯 개수가 물리적 한계에 부딪혀서, 아예 CPU를 여러 개 박아버려 대역폭을 뻥튀기하기 위함

#### 한줄 요약

- CPU 하나로 안 되니까 여러 개를 박고, 램을 합쳐서 한 대의 거대한 컴퓨터처럼 쓰는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인터커넥트 패브릭(Interconnect Fabric)**: CPU 1번과 2번 사이에 깔린 초고속 전용 고속도로로, 남의 동네 램 쓸 때나 캐시 맞출 때 빛의 속도로 데이터를 나르는 통로이다.
- **로컬 대 원격 접근(Local vs Remote Access)**: 자기 램 쓸 때(로컬)는 번개같이 빠르지만, 고속도로 타고 남의 램 빌려 쓸 때(원격)는 굼벵이처럼 느려지는 치명적인 속도 차이 현상이다.

</details>

- 수십 개의 코어와 메모리 구역이 찢어져 있어도, 프로그램한테는 통짜 램 하나인 것처럼 사기 치는 **대칭형 다중 처리(SMP)** 기반임.
- 1번 CPU가 2번 CPU 쪽 램을 쓸 때 데이터가 안 꼬이게 멱살 잡고 캐시를 동기화하는 **ccNUMA** 아키텍처가 필수적임.
- 자기 램을 쓸 때(Local)랑 남의 램을 빌려 쓸 때(Remote)의 지연 시간 갭(**로컬 대 원격 접근**)이 폭발해서 이거 통제하는 게 핵심임.

#### 한줄 요약

- 다 합쳐서 하나처럼 쓰지만, 남의 구역 램(원격)을 쓸 때 느려지는 딜레이를 어떻게든 줄여야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **누마 노드(NUMA Node)**: "내 밥그릇은 내가 챙긴다" 모드로 뭉친 1개 CPU 코어 뭉치와, 바로 옆에 직결된 자기 구역의 전용 로컬 램 한 세트이다.
- **퍼스트 터치 할당(First-Touch Allocation)**: 프로그램이 처음 메모리를 달라고 징징대면, 무조건 그 프로그램이 돌고 있는 CPU의 제일 가까운 램(로컬)부터 꽉꽉 채워주는 절대 규칙이다.

</details>

```text
[ 뼛속까지 찢어진 멀티소켓 NUMA 십자포화 프레임워크 ]
[ OS 누마 스케줄러 (통제관) ]
           │
 ┌─────────┴─────────┐
 ▼                   ▼
[ 누마 노드 0 ]      [ 누마 노드 1 ]
(CPU 0 + 로컬 램 0)  (CPU 1 + 로컬 램 1)
       │                 │
       └──── (고속도로) ──┘
   [ 인터커넥트 패브릭 (UPI) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **누마 노드** (Socket) | "내 밥그릇은 내가 챙긴다" 모드로 뭉친 1개 CPU 코어 뭉치와 바로 옆에 직결된 자기 구역의 전용 로컬 램 |
| **인터커넥트 패브릭** | 남의 동네 램 빌려 쓸 때 빛의 속도로 연결해 주고, 캐시 안 꼬이게 빡세게 검사하는 소켓 간 고속도로(UPI 등) |
| OS 누마 스케줄러 | 프로그램이 메모리 달라고 징징대면 "너 실행되는 동네 램 써라" 하고 꽂아주는 **퍼스트 터치 할당** 통제관 |
| I/O 서브시스템 | 랜카드나 그래픽카드도 아무 데나 꽂지 말고, 제일 가까운 누마 노드(CPU) 관할에 꽂게 라우팅 묶어주는 시스템 |

#### 한줄 요약

- CPU와 램 세트(누마 노드)를 고속도로(인터커넥트)로 묶고, 스케줄러가 남의 동네 안 넘어가게 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **누마씨티엘 / 시피유 친화도(Numactl / CPU Affinity)**: 스레드가 1번 CPU에서 2번 CPU로 멋대로 도망 못 가게 "넌 여기서만 돌아라!" 하고 멱살 잡고 묶어버리는 강제 명령이다.

</details>

```text
[ 뼛속까지 찢어진 누마 노드 십자포화 메모리 맵핑 흐름 ]
                                 │
                                 ▼
   [ 1. 목줄 채우기: 스레드가 도망 못 가게 특정 CPU에 친화도로 묶어버림 ]
                                 │
                                 ▼
 [ 2. 밥그릇 할당: 첫 메모리 터치 시, 무조건 돌고 있는 CPU의 찐 로컬 램에 욱여넣음 ]
                                 │
                                 ▼
  [ 3. 얌체 짓 감시: 스레드가 고속도로 타고 남의 동네 램을 파먹는지 레이더 돌림 ]
                                 │
                 ┌───────────────┴───────────────┐
           ( 로컬 잘 쓸 때 )               ( 남의 동네 파먹을 때 )
                 ▼                               ▼
            [ 칭찬 후 유지 ]          [ 4. 이사 강제 집행: 스레드나 메모리 ]
                                      [ 통째로 멱살 잡고 옆 동네로 쫓아냄 ]
                                                 │
                                                 ▼
                                     [ 5. 검증 뺑뺑이: 다시 감시함 ]
```

### 동작 원리

1. 목줄 채우기(선호도 지정): **누마씨티엘** 툴로 스레드가 특정 CPU 동네에서 못 벗어나게 **시피유 친화도** 목줄을 채움.
2. 자기 밥그릇 할당: **퍼스트 터치 할당** 발동으로, 스레드가 도는 CPU 직결 램(로컬)에 데이터를 욱여넣음.
3. 얌체 짓 감시: 스레드가 굳이 고속도로(**인터커넥트 패브릭**)를 타서 남의 램을 파먹는지 레이더로 잼.
4. 이사 강제 집행: 남의 램 파먹는 비율이 높으면(병목 폭발), 아예 스레드나 메모리 통째로 멱살 잡고 램이 있는 동네로 쫓아냄.
5. 검증 뺑뺑이: 이사시켜놓고 또 얌체 짓 하는지 십자포화 감시함.

#### 한줄 요약

- 스레드를 한 CPU에 묶고 로컬 램을 쓰게 한 뒤, 자꾸 남의 램을 파먹으면 아예 그쪽으로 강제 이사시킨다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **균일 메모리 접근(Uniform Memory Access, UMA)**: 흔히 쓰는 깡통 PC처럼, CPU 1개가 전체 램을 아무 딜레이 눈치 안 보고 평등하게 다 파먹는 맘 편한 구조이다.

</details>

| 비교 항목 | **멀티소켓 서버** (ccNUMA) | **단일 소켓 깡통 서버** (UMA) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 인메모리 DB(SAP HANA)처럼 램을 수 테라바이트씩 쳐먹는 엔터프라이즈 괴물 환경일 시 | 그냥 어지간한 웹 서버나 가상 머신 몇 개 돌리는 평범한 서버 구축 시 |
| 아키텍처 핵심 구현 특징 | 메인보드 한 판에 CPU를 2개, 4개씩 쑤셔 박고 램 슬롯 수백 개를 억지로 하나로 이어붙임 | 그냥 우리가 아는 흔한 PC처럼 메인보드 한가운데 CPU 1개 박고 램 꽂아 쓰는 무난한 구조 |
| 극복해야 할 태생적 한계점 | 코드가 남의 동네 램(Remote) 쑤시러 다니는 순간 성능이 반토막 나는 끔찍한 누마(NUMA) 지옥 발동 | 코어나 램을 늘리고 싶어도 CPU 하나가 감당할 수 있는 한계선에서 성장이 멈춰버림 |

#### 한줄 요약

- 단일 소켓(UMA)은 편하지만 한계가 명확하고, 멀티소켓(NUMA)은 괴물 성능을 내지만 램 딜레이 관리가 지옥이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 전혀 상관없는 두 데이터가 하필 같은 캐시 줄에 들어가서, 1번 CPU랑 2번 CPU가 자기 거 맞출려고 무의미하게 싸우며 시스템을 뻗게 만드는 버그이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드가 1번 CPU에서 2번 CPU로 멋대로 도망 다녀서 남의 동네 램 퍼오느라 지연 폭발하는 재앙 | **누마씨티엘(Numactl)**로 스레드와 메모리를 한 동네에 멱살 잡고 못 벗어나게 묶어버림 | 원격 접근(Remote Access) 병목을 씹어먹고 지연시간 없는 극강의 로컬 대역폭 사수 |
| 독립된 데이터인데 하필 같은 캐시 라인에 묶여서 1번, 2번 CPU가 무의미하게 싸우는 **거짓 공유** 발발 | 캐시 라인(64바이트) 꽉꽉 채워 패딩(Padding) 박아서 스레드 간 겹치는 공간을 찢어발김 | 인터커넥트 고속도로 막히는 쓸데없는 무효화 트래픽을 100% 원천 차단 |
| 가상 머신(VM) 하나에 던져준 가짜 램이 1번, 2번 CPU 양다리를 걸치고 박혀서 렉이 미쳐 날뜀 | 가상 머신한테도 하이퍼바이저 단에서 누마 피닝(NUMA Pinning)을 강제로 먹여서 한 동네 구겨 넣음 | 구름 위에 떠 있는 가상 머신마저도 물리적인 누마 딜레이(Latency)의 마수에서 구출 |

#### 한줄 요약

- 스레드와 메모리를 한 동네로 묶고(Numactl), 캐시 라인이 안 겹치게 찢으며, 가상 머신도 강제로 묶어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **멀티소켓 확장 기준(Multi-Socket Adoption Criteria)**: 이 작업이 단일 CPU로 버틸 수 있는지, 아니면 누마(NUMA) 지옥을 각오하고 괴물 서버를 띄워야 하는지 견적을 재보는 기준표이다.

</details>

- **멀티소켓 확장 기준** 원칙에 따라, 램 몇 테라 필요한 인메모리 DB는 닥치고 **멀티소켓**, 자잘한 웹서버는 **단일 소켓** 깡통 여러 대 채택 기조 확립함

#### 한줄 요약

- 램이 미친 듯이 필요한 괴물 작업엔 멀티소켓을 쓰고, 어지간하면 편하게 단일 소켓 여러 대를 써라.
