## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티소켓 서버(Multi-Socket Server)**: 단일 메인보드에 2개 이상의 독립된 CPU 소켓(Socket)을 장착하고 고속 점대점 직렬 인터커넥트로 연결하여 단일 운영체제 하에서 거대한 대칭형 공유 메모리를 구성하는 서버.
- **대칭형 다중 처리(Symmetric Multiprocessing, SMP)**: 모든 CPU 코어가 단일 OS 아래에서 전체 시스템 메모리와 입출력 장치를 동등한 권한으로 공유하는 병렬 컴퓨팅 구조.
- **캐시 일관성 NUMA(Cache-Coherent NUMA, ccNUMA)**: 물리 메모리가 소켓별로 분산 배치되어 접근 거리에 따른 지연시간 편차가 존재하지만, 하드웨어 디렉터리 프로토콜이 전체 소켓의 캐시 일관성을 완벽히 보장하는 아키텍처.

</details>

- 정의/개념: 복수의 CPU 소켓을 고속 인터커넥트로 연결해 단일 공유 메모리를 구성하는 **멀티소켓 서버** 아키텍처
- 배경/필요성: 단일 CPU 소켓의 물리적 실리콘 면적, 전력 한계(TDP) 및 메모리 채널 수 제약으로 인한 **단일 노드 스케일업(Scale-Up) 성능 한계를 극복하고, 수백 코어/수십 테라바이트 단일 공유 메모리 공간 확보** 필요

#### 한줄 요약
- 다중 CPU 소켓을 고속 버스로 결합하여 단일 OS 아래 대규모 코어와 테라바이트급 메모리를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **소켓 간 인터커넥트(Interconnect Fabric)**: CPU 소켓 간에 캐시 일관성 스눕(Snoop) 패킷과 원격 메모리 데이터를 중계하는 점대점 고속 직렬 버스(Intel UPI, AMD Infinity Fabric).
- **NUMA 비율(NUMA Ratio)**: 로컬 메모리 접근 지연시간(약 80ns) 대비 타 소켓의 원격 메모리(Remote Memory) 접근 지연시간(약 140ns)의 비율(보통 1.5~2.0배).

</details>

- 단일 OS 투명 공유: 수백 개 코어가 분산 메모리를 단일 공간으로 공유하는 **대칭형 다중 처리(SMP)**
- 하드웨어 캐시 일관성: **디렉터리 프로토콜** 기반 소켓 간 캐시 데이터 일관성 하드웨어 보장
- 비균일 메모리 접근: 물리적 거리에 따른 지연 편차를 갖는 **ccNUMA** 구조 및 **메모리 지역성** 최적화 요구

#### 한줄 요약
- 하드웨어 캐시 일관성을 유지하는 공유 메모리 구조이며, 원격 메모리 접근 지연을 줄이는 지역성 설계가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **UPI / Infinity Fabric**: 인텔과 AMD의 독자적인 소켓 간 고속 점대점 인터커넥트 버스로 초당 수십 기가트랜스퍼(GT/s)의 대역폭을 제공하는 상호연결 패브릭.

</details>

```text
[2-소켓 ccNUMA 서버 하드웨어 아키텍처]
 ├── NUMA 노드 0 (소켓 0)
 │   ├── CPU 코어 클러스터 (L1 / L2 / L3 캐시)
 │   ├── 로컬 메모리 컨트롤러 ────────── 로컬 DRAM 채널 0 (~80ns 초저지연)
 │   └── 소켓 0 로컬 PCIe Root Complex ─ 로컬 NVMe SSD / NIC 0
 ├── 소켓 간 인터커넥트 패브릭 ──────── 점대점 패브릭 (Intel UPI / AMD IF, ~140ns)
 └── NUMA 노드 1 (소켓 1)
     ├── CPU 코어 클러스터 (L1 / L2 / L3 캐시)
     ├── 로컬 메모리 컨트롤러 ────────── 로컬 DRAM 채널 1 (~80ns 초저지연)
     └── 소켓 1 로컬 PCIe Root Complex ─ 로컬 NVMe SSD / NIC 1
```

선의 의미: 가지(`├──`, `└──`)는 하드웨어 소속 및 소켓 간 연결 관계; 로컬 메모리는 80ns에 직접 접근하며 원격 메모리는 UPI/IF 패브릭을 경유하여 140ns 지연으로 접근함

| 구성요소 | 책임 |
|:---|:---|
| NUMA 노드 | 코어와 DRAM의 **로컬 메모리 도메인** |
| 인터커넥트 패브릭 | 원격 전송과 **캐시 일관성 스눕** |
| OS NUMA 스케줄러 | **First-Touch·페이지 이동** |
| 로컬 PCIe 컨트롤러 | 소켓별 **로컬 I/O 라우팅** |

#### 한줄 요약
- 메모리 제어와 PCIe 제어가 모두 소켓 안으로 들어와 각 노드가 자기 코어의 요청을 스스로 끝내고, 패브릭에는 그 경계를 넘는 접근과 캐시 일관성 스눕만 남으므로 코어와 장치를 어느 노드에 붙이느냐가 곧 경로 길이가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **First-Touch 정책**: 리눅스 커널에서 프로세스 스레드가 메모리를 처음 쓰기(Write)하는 시점에 해당 스레드가 실행 중인 CPU 코어의 로컬 NUMA 노드에 물리 페이지를 할당하는 기본 정책.

</details>

```text
[메모리 할당 및 최초 쓰기 요청]
                │
                ▼
1. First-Touch 정책 기반 로컬 DRAM 물리 페이지 할당
                │
                ▼
2. 스레드 메모리 읽기 및 쓰기 주소 판별
                │
                ▼
3. 로컬 메모리 인출 또는 소켓 간 패브릭 원격 전송
                │
                ▼
4. AutoNUMA 원격 접근 감지 및 페이지 마이그레이션
                │
                ▼
[하드웨어 캐시 일관성 트랜잭션 완료]
```

분기 결과: 로컬 메모리 접근은 **초저지연**으로 즉시 처리되며 원격 접근은 AutoNUMA를 통해 **로컬 페이지로 자동 재배치**됨

**동작 원리**

1. First-Touch 정책 기반 로컬 DRAM 물리 페이지 할당
2. 스레드 메모리 읽기 및 쓰기 주소 판별
3. 로컬 메모리 인출 또는 소켓 간 패브릭 원격 전송
4. AutoNUMA 원격 접근 감지 및 페이지 마이그레이션

#### 한줄 요약
- 로컬로 갈리면 인출이 소켓 내부에서 끝나지만 원격으로 갈리면 참조마다 소켓 간 패브릭 홉이 덧붙으므로, AutoNUMA는 그 반복 비용을 페이지 복사 한 번으로 상환하는 선택이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **분산 비공유 클러스터(Shared-Nothing MPP)**: 노드 간 메모리를 일체 공유하지 않고 고속 네트워크 메시지(MPI, TCP)로 데이터를 교환하는 대규모 분산 구조.

</details>

| 서버 컴퓨팅 아키텍처 | 멀티소켓 서버 (ccNUMA / SMP) | 단일 소켓 서버 (1-Socket UMA) | 분산 비공유 클러스터 (MPP / Scale-Out) |
|:---|:---|:---|:---|
| 메모리 주소 공간 | **물리 분산, 논리 단일 공유** | 단일 균등 메모리 접근 (UMA) | 노드별 독립 메모리 (Shared-Nothing) |
| 캐시 일관성 보장 | **하드웨어 디렉터리 ccNUMA** | 단일 소켓 내부 캐시 일관성 | **하드웨어 일관성 없음 (네트워크)** |
| 최대 확장성 한계 | 수십 TB 단일 메모리 | 단일 CPU 물리적 한계 | **수만 대 노드 무제한 확장** |
| 주요 적용 분야 | **대형 RDBMS, 인메모리 DB** | 웹 서버, 마이크로서비스 | **빅데이터, AI 분산 학습** |

#### 한줄 요약
- 단일 대용량 인메모리 DB는 멀티소켓 ccNUMA, 경량 서비스는 단일 소켓, 대규모 AI 분산은 MPP 클러스터가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 사용하는 독립된 변수들이 동일한 64바이트 캐시 라인에 우연히 함께 위치하여 불필요한 캐시 무효화(Invalidation) 트래픽이 소켓 간에 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드 이동으로 인한 원격 지연 급증 | **numactl / taskset** 기반 CPU 및 NUMA 노드 바인딩 | 메모리 지역성 확보 및 **패브릭 병목 차단** |
| 64바이트 캐시 라인 공유 시 버스 폭증 | 64바이트 단위 **데이터 구조체 정렬 및 패딩** | **거짓 공유(False Sharing)** 무효화 트래픽 차단 |
| 원격 소켓 I/O 장치 접근 시 대역폭 저하 | I/O 인터럽트 및 DMA 처리를 **로컬 NUMA 코어에 바인딩** | 소켓 간 UPI 대역폭 낭비 방지 및 **I/O 극대화** |

#### 한줄 요약
- 실무에서는 numactl 노드 바인딩으로 지연을 잡고, 64B 캐시 정렬로 버스를 아끼며, I/O 바인딩으로 처리량을 극대화한다.

## Ⅶ. 결론

- 단일 OS 기반 대규모 인메모리 데이터베이스(SAP HANA, Oracle RAC) 및 엔터프라이즈 스케일업 워크로드의 **핵심 하드웨어 플랫폼(2S/4S/8S ccNUMA)**으로 확립되었으며, 최근에는 소켓 간 고유 인터커넥트(UPI, IF)를 넘어 **CXL 2.0/3.0 기반 이기종 메모리 풀링 및 분산 공유 메모리 패브릭**으로 확장

#### 한줄 요약
- 멀티소켓 서버는 하드웨어 캐시 일관성 기반 단일 메모리 공간을 제공하며, 메모리 지역성 최적화가 성능의 핵심이다.
