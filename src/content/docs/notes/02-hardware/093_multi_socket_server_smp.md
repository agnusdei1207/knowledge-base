## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티소켓 서버(Multi-Socket Server)**: 단일 메인보드에 2개 이상의 독립된 CPU 소켓(Socket)을 장착하고 고속 점대점 직렬 인터커넥트로 연결하여 단일 운영체제 하에서 거대한 대칭형 공유 메모리를 구성하는 서버.
- **대칭형 다중 처리(Symmetric Multiprocessing, SMP)**: 모든 CPU 코어가 단일 OS 아래에서 전체 시스템 메모리와 입출력 장치를 동등한 권한으로 공유하는 병렬 컴퓨팅 구조.
- **캐시 일관성 NUMA(Cache-Coherent NUMA, ccNUMA)**: 물리 메모리가 소켓별로 분산 배치되어 접근 거리에 따른 지연시간 편차가 존재하지만, 하드웨어 디렉터리 프로토콜이 전체 소켓의 캐시 일관성을 완벽히 보장하는 아키텍처.

</details>

- 정의/개념: 다수의 물리 CPU 소켓을 고속 점대점 인터커넥트(Intel UPI, AMD Infinity Fabric)로 결합하여 단일 공유 메모리 공간을 제공하는 **멀티소켓 서버(ccNUMA / SMP) 아키텍처**
- 배경/필요성: 단일 소켓 CPU의 물리적 코어 수(최대 64~128코어) 및 메모리 채널 한계로 인한 **초대형 인메모리 DB(SAP HANA) 및 고밀도 가상화 컴퓨팅의 확장성 제약 극복**

#### 한줄 요약
- 다중 CPU 소켓을 고속 버스로 결합하여 단일 OS 아래 대규모 코어와 테라바이트급 메모리를 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **소켓 간 인터커넥트(Interconnect Fabric)**: CPU 소켓 간에 캐시 일관성 스눕(Snoop) 패킷과 원격 메모리 데이터를 중계하는 점대점 고속 직렬 버스(Intel UPI, AMD Infinity Fabric).
- **NUMA 비율(NUMA Ratio)**: 로컬 메모리 접근 지연시간(약 80ns) 대비 타 소켓의 원격 메모리(Remote Memory) 접근 지연시간(약 140ns)의 비율(보통 1.5~2.0배).

</details>

- 단일 OS 투명 공유: 수백 개의 CPU 코어가 테라바이트급 분산 메모리를 단일 평면 주소 공간으로 투명하게 공유하는 **SMP(대칭형 다중 처리)**
- 하드웨어 캐시 일관성: 디렉터리 기반 MESI/MOESI 프로토콜을 통해 소켓 간 L1/L2/L3 캐시 데이터의 무결성을 하드웨어 레벨에서 완전 보장
- 비균일 메모리 지연: 물리적 거리에 따라 지연시간이 달라지는 **ccNUMA** 구조로 인해 OS 및 소프트웨어의 **메모리 지역성(Locality)** 최적화 필수

#### 한줄 요약
- 하드웨어 캐시 일관성을 유지하는 공유 메모리 구조이며, 원격 메모리 접근 지연을 줄이는 지역성 설계가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **UPI / Infinity Fabric**: 인텔과 AMD의 독자적인 소켓 간 고속 점대점 인터커넥트 버스로 초당 수십 기가트랜스퍼(GT/s)의 대역폭을 제공하는 상호연결 패브릭.

</details>

```text
[2-소켓 ccNUMA 서버 하드웨어 아키텍처]
 ┌─ [NUMA 노드 0 (소켓 0)]
 │   ├─ CPU 코어 클러스터 (L1 / L2 / L3 캐시)
 │   ├─ 로컬 메모리 컨트롤러 ──► [로컬 DRAM 채널 0] (~80ns 초저지연)
 │   └─ 소켓 0 로컬 PCIe Root Complex ──► [로컬 NVMe SSD / NIC 0]
 │
 ├─ [소켓 간 인터커넥트 패브릭 (Intel UPI / AMD IF)] ── 점대점 고속 패브릭 (~140ns 원격 통신)
 │
 └─ [NUMA 노드 1 (소켓 1)]
     ├─ CPU 코어 클러스터 (L1 / L2 / L3 캐시)
     ├─ 로컬 메모리 컨트롤러 ──► [로컬 DRAM 채널 1] (~80ns 초저지연)
     └─ 소켓 1 로컬 PCIe Root Complex ──► [로컬 NVMe SSD / NIC 1]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 소켓 간 연결 관계; 로컬 메모리는 80ns에 직접 접근하며 원격 메모리는 UPI/IF 패브릭을 경유하여 140ns 지연으로 접근함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **NUMA 노드 (Socket)**| 단일 CPU 소켓단 | CPU 코어 그룹과 해당 소켓의 메모리 컨트롤러에 직결된 로컬 DRAM 기본 단위 | 로컬 메모리 도메인 |
| **인터커넥트 패브릭** | 소켓 간 연결단 | 소켓 간 원격 메모리 읽기/쓰기 패킷 전송 및 **하드웨어 캐시 일관성 디렉터리 스눕** | Intel UPI / AMD IF |
| **OS NUMA 스케줄러** | 운영체제 커널단 | **First-Touch 정책** 및 AutoNUMA 페이지 마이그레이션으로 메모리 지역성 극대화 | 커널 스케줄러 |
| **로컬 PCIe 컨트롤러**| 소켓 I/O단 | 각 NUMA 노드에 직결된 고속 I/O 디바이스(100GbE NIC, NVMe) 통제 | 로컬 I/O 라우팅 |

#### 한줄 요약
- 멀티소켓 서버는 소켓별 NUMA 노드, 고속 인터커넥트 패브릭, OS NUMA 스케줄러 및 로컬 PCIe 컨트롤러로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **First-Touch 정책**: 리눅스 커널에서 프로세스 스레드가 메모리를 처음 쓰기(Write)하는 시점에 해당 스레드가 실행 중인 CPU 코어의 로컬 NUMA 노드에 물리 페이지를 할당하는 기본 정책.

</details>

```text
1. 애플리케이션 스레드가 메모리 동적 할당(malloc) 후 최초 쓰기(First Touch) 발생
                      │
                      ▼
2. OS 커널: First-Touch 정책에 따라 현재 실행 중인 코어의 로컬 DRAM 0에 물리 페이지 할당
                      │
                      ▼
3. 스레드가 데이터 읽기/쓰기 명령어 실행
                      │
                      ▼
4. 접근 대상 물리 주소가 현재 실행 코어의 로컬 소켓 메모리인가?
   ┌──────────────────┴──────────────────┐
[ 로컬 메모리 주소 (Local Access) ]   [ 타 소켓 원격 메모리 주소 (Remote) ]
   │                                     │
   ▼                                     ▼
5. 로컬 메모리 컨트롤러 직결 인출        5. 소켓 간 인터커넥트(UPI/IF) 경유 패킷 전송
   (~80ns 초저지연)                      (~140ns, NUMA Penalty 지연 발생)
   │                                     │
   │                                     ▼
   │                                  6. AutoNUMA 커널 데몬이 원격 접근 빈도 감지
   │                                     ➔ 해당 페이지를 스레드 로컬 노드로 백그라운드 마이그레이션
   └──────────────────┬──────────────────┘
                      │
                      ▼
7. 하드웨어 캐시 일관성 유지 하에 트랜잭션 정상 완료
```

분기 결과: **로컬 접근은** 80ns로 즉시 처리되며, **원격 접근은** 인터커넥트 지연이 발생하나 AutoNUMA를 통해 로컬로 자동 재배치됨

#### 한줄 요약
- First-Touch 할당 ➔ 로컬/원격 메모리 접근 분기 ➔ AutoNUMA 자동 마이그레이션 ➔ 트랜잭션 완료 순으로 처리된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **분산 비공유 클러스터(Shared-Nothing MPP)**: 노드 간 메모리를 일체 공유하지 않고 고속 네트워크 메시지(MPI, TCP)로 데이터를 교환하는 대규모 분산 구조.

</details>

| 서버 컴퓨팅 아키텍처 | 멀티소켓 서버 (ccNUMA / SMP) | 단일 소켓 서버 (1-Socket UMA) | 분산 비공유 클러스터 (MPP / Scale-Out) |
|:---|:---|:---|:---|
| 메모리 주소 공간 | **물리 분산, 논리 단일 공유 메모리** | 단일 균등 메모리 접근 (UMA) | 노드별 독립 메모리 (Shared-Nothing) |
| 캐시 일관성 보장 | **하드웨어 디렉터리 ccNUMA 보장** | 단일 소켓 내부 캐시 일관성 | **하드웨어 일관성 없음 (네트워크 통신)** |
| 최대 확장성 한계 | 수십 TB 단일 메모리 (원격 지연 존재)| 단일 CPU 물리적 한계 (초저지연) | **수만 대 노드 무제한 수평 확장** |
| 주요 적용 분야 | **초대형 RDBMS, SAP HANA, 가상화 팜** | 웹 서버, 마이크로서비스, 단일 DB | **빅데이터(Hadoop), 초거대 AI 분산 학습** |

#### 한줄 요약
- 단일 대용량 인메모리 DB는 멀티소켓 ccNUMA, 경량 서비스는 단일 소켓, 대규모 AI 분산은 MPP 클러스터가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 사용하는 독립된 변수들이 동일한 64바이트 캐시 라인에 우연히 함께 위치하여 불필요한 캐시 무효화(Invalidation) 트래픽이 소켓 간에 폭증하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스레드 코어 이동으로 인한 원격 메모리 접근 지연 급증 | **numactl / taskset 기반 CPU 코어 및 NUMA 메모리 노드 바인딩** | 메모리 지역성 100% 확보 및 소켓 간 인터커넥트 병목 차단 |
| 동일 64바이트 캐시 라인 공유로 인한 **거짓 공유(False Sharing)** | **64바이트 단위 데이터 구조체 정렬(Align) 및 패딩 적용** | 소켓 간 불필요한 캐시 무효화 버스 트래픽 원천 차단 |
| 원격 소켓 I/O 장치(100GbE NIC/NVMe) 접근 시 대역폭 저하 | **I/O 인터럽트 및 DMA 처리를 로컬 NUMA 코어에 바인딩** | 소켓 간 UPI 대역폭 낭비 방지 및 I/O 처리율 극대화 |

#### 한줄 요약
- 실무에서는 numactl 노드 바인딩으로 지연을 잡고, 64B 캐시 정렬로 버스를 아끼며, I/O 바인딩으로 처리량을 극대화한다.

## Ⅶ. 결론

- 초대용량 인메모리 데이터베이스(SAP HANA) 및 엔터프라이즈 가상화 인프라를 구축할 때 **하드웨어 캐시 일관성을 보장하는 4-Socket ccNUMA 멀티소켓 서버를 표준 선정**하고, 원격 메모리 지연을 최소화하기 위해 **numactl 노드 바인딩 및 64B 캐시 라인 정렬**을 적용하며, 장기적으로는 **CXL 기반 메모리 풀링 아키텍처**와 연계하는 고성능 멀티소켓 인프라 확립

#### 한줄 요약
- 멀티소켓 서버는 하드웨어 캐시 일관성 기반 단일 메모리 공간을 제공하며, 메모리 지역성 최적화가 성능의 핵심이다.
