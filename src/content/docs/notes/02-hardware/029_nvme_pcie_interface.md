## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NVMe(Non-Volatile Memory Express)**: 고속 PCIe 버스 상에서 초고속 플래시 스토리지의 병렬 처리 성능을 극대화하기 위해 다중 큐 기반으로 설계된 호스트 컨트롤러 인터페이스 규격.
- **PCIe(Peripheral Component Interconnect Express)**: 고속 직렬 점대점 레인을 기반으로 프로세서와 주변 장치를 연결하는 표준 확장 버스.
- **락리스 큐(Lockless Multi-Queue)**: 멀티코어 환경에서 CPU 코어별로 독립된 SQ/CQ를 할당하여 스핀락 경합 없이 병렬 I/O를 처리하는 구조.

</details>

- 정의/개념: 고속 PCIe 직렬 버스 위에서 최대 64K개의 다중 큐(SQ/CQ)와 락리스(Lockless) 구조로 NAND 플래시의 병렬 I/O 성능을 극대화하는 호스트 컨트롤러 인터페이스 규격
- 배경/필요성: 단일 큐(Queue Depth 32)와 레거시 AHCI/SATA 병목을 극복하고, 멀티코어 환경에서 **수백만 IOPS급 초고속 플래시 병렬 처리 및 저지연(Sub-10$\mu$s) 확보**

#### 한줄 요약

- PCIe 버스 위에서 **다중 큐(64K)와 락리스 도어벨 통지**로 플래시 병렬성 극대화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제출 큐(Submission Queue, SQ)**: 호스트 CPU가 블록 읽기/쓰기 명령 엔트리(64B)를 등록하는 원형 큐.
- **완료 큐(Completion Queue, CQ)**: NVMe 컨트롤러가 명령 수행 완료 후 상태 결과(16B)를 기록하는 원형 큐.
- **도어벨 레지스터(Doorbell Register)**: 호스트가 새로운 SQ 엔트리를 추가했거나 CQ 엔트리를 소비했음을 컨트롤러에 알리는 MMIO 레지스터.
- **MSI-X(Message Signaled Interrupts-Extended)**: 다중 코어에 완료 인터럽트를 1:1로 분산 매핑하는 메시지 기반 인터럽트.

</details>

- 코어별 독립 **제출 큐(SQ)** 및 **완료 큐(CQ)** 매핑을 통한 전역 락 경합 및 스케줄링 오버헤드 원천 제거
- **도어벨 레지스터** 통지와 버스 마스터 DMA 방식을 결합하여 CPU의 I/O 개입 지연 극소화
- **MSI-X** 인터럽트 벡터를 활용하여 수백만 IOPS의 고속 I/O 완료 처리를 멀티코어로 균등 분산

#### 한줄 요약

- **코어별 SQ/CQ 전용 할당·도어벨 통지·MSI-X 인터럽트**로 락 경합 및 지연 제거

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Host Memory Buffer(HMB)**: DRAM-less NVMe SSD가 호스트 메인 메모리의 일부 공간을 FTL 매핑 테이블 캐시로 대여 사용하는 기술.
- **NVMe Controller**: SSD 내부에 탑재되어 PCIe PHY 패킷 수신, SQ/CQ 파싱, FTL 변환 및 플래시 채널 제어를 총괄하는 SoC.

</details>

```text
[ NVMe 다중 큐 및 PCIe 인터페이스 구조도 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 멀티코어 CPU (Core 0 ~ Core N)                       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 호스트 메모리 (Host Memory: Lockless Multi-Queue Buffer)     │
│  ├─ Core 0 : [ Submission Queue 0 ] ── [ Completion Queue 0 ]│
│  └─ Core N : [ Submission Queue N ] ── [ Completion Queue N ]│
└──────────────────────────────┬──────────────────────────────┘
                               │
[ 통지용 Doorbell Register ] ── (PCIe Gen4/5 x4 레인)
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ NVMe 컨트롤러 SoC (FTL 매핑 및 8/16개 플래시 채널 병렬 제어) │
│  ├─ DMA 엔진 / Command Fetch & Arbitration Unit             │
│  └─ 다중 낸드 플래시 칩 (NAND Flash Dies)                   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트 메모리 버퍼(SQ/CQ), 도어벨 레지스터, PCIe 레인 및 NVMe 컨트롤러 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 제출 큐(SQ) 및 완료 큐(CQ) | 호스트의 입출력 명령 엔트리 게시 및 장치의 작업 완료 상태 교환 제공 |
| 도어벨 레지스터 | 큐 꼬리 및 머리 포인터 변경 통지를 통한 호스트와 장치 간 직접 신호 전달 |
| 물리 레인 인터페이스 (PCIe) | 명령 및 데이터 패킷의 초고속 직접 메모리 접근(DMA) 물리 경로 제공 |
| 메시지 시그널 인터럽트 (MSI-X) | 다중 코어 아키텍처에 특화된 분산형 작업 완료 인터럽트 통보 처리 제공 |

#### 한줄 요약

- **제출 큐(SQ)·완료 큐(CQ)·도어벨 레지스터·MSI-X 벡터**의 유기적 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DMA Read/Write**: CPU 개입 없이 NVMe 컨트롤러가 호스트 메모리에서 명령을 읽어오고(Fetch), 사용자 데이터를 직접 송수신하는 메커니즘.

</details>

```text
[ 호스트 애플리케이션 I/O 시스템 콜 ]
                  │
                  ▼
   [ 1. 호스트 메모리 SQ에 64B 명령 등록 ]
                  │
                  ▼
   [ 2. SQ Tail 도어벨 레지스터에 쓰기 (MMIO) ]
                  │
                  ▼
   [ 3. NVMe 컨트롤러가 DMA로 SQ 명령 인출 (Fetch) ]
                  │
                  ▼
   [ 4. FTL 주소 변환 후 낸드 플래시 채널 병렬 실행 ]
                  │
                  ▼
   [ 5. 데이터 DMA 전송 및 호스트 메모리 CQ에 16B 완료 기록 ]
                  │
                  ▼
   [ 6. MSI-X 인터럽트 발생 ──> 호스트가 CQ Head 도어벨 갱신 ]
```

**동작 원리**

1. **명령 등록**: 호스트 드라이버가 호스트 메모리의 코어 전용 SQ에 64바이트 I/O 명령 엔트리 기록
2. **도어벨 통지**: 호스트가 PCIe MMIO 영역의 SQ Tail 도어벨 레지스터에 새로운 꼬리 번호 기록
3. **명령 인출**: NVMe 컨트롤러가 DMA를 구동하여 호스트 메모리에서 명령을 인출하고 큐 스케줄링
4. **플래시 실행**: 컨트롤러 FTL이 LBA를 PBA로 변환하여 다중 플래시 채널로 병렬 읽기/쓰기 수행
5. **데이터 전송 및 CQ 기록**: 데이터를 호스트 버퍼로 DMA 전송하고, 호스트 메모리의 CQ에 완료 상태 기록
6. **인터럽트 및 회수**: MSI-X 인터럽트를 발생시켜 해당 코어에 통보하고, 호스트는 CQ Head 도어벨을 갱신하여 큐 회수

#### 한줄 요약

- SQ 기록 $\to$ **도어벨 통지 $\to$ DMA 명령 인출 및 플래시 실행 $\to$ CQ 기록 및 MSI-X 완료**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **NVMe vs AHCI**:
  - NVMe: PCIe 기반, 최대 64K개 큐, 큐당 64K 깊이, 수백만 IOPS, <10$\mu$s 지연
  - AHCI: SATA 기반, 단일 큐, 큐당 32 깊이, 수만 IOPS, ~100$\mu$s 지연

</details>

| 비교 항목 | NVMe (PCIe 기반) | AHCI (SATA 기반) |
|:---|:---|:---|
| 물리 버스 및 대역폭 | PCIe 4.0/5.0 (레인당 2~4GB/s, x4 기준 8~16GB/s) | SATA 3.0 (최대 6Gbps, 실효 ~600MB/s) |
| 큐 구조 및 동시성 | 최대 65,535개 다중 큐 (코어별 독립 큐, Lockless) | 단일 명령 큐 1개 (단일 Lock으로 인한 멀티코어 병목) |
| 최대 큐 깊이 (QD) | 큐당 최대 64K (65,536) 개 엔트리 | 큐당 최대 32개 엔트리 (NCQ) |
| 인터럽트 처리 방식 | 코어 분산형 다중 메시지 시그널 인터럽트 (MSI-X) | 단일 코어 집중형 레거시 핀/단일 인터럽트 |

#### 한줄 요약

- NVMe는 **다중 큐 기반 수백만 IOPS**, AHCI는 **단일 큐 기반 레거시 병목**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **io_uring**: 리눅스 커널의 최신 비동기 I/O 프레임워크로, 사용자-커널 공간 간 SQ/CQ 링 버퍼 공유를 통해 시스템 콜 오버헤드와 인터럽트를 제거.
- **적응형 폴링(Adaptive Polling / Hybrid Polling)**: 인터럽트 대기 대신 CPU가 CQ를 직접 폴링하여 Sub-microsecond 초저지연을 달성하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 큐 깊이를 과도하게 증가시킬 경우 큐 포화로 인한 **꼬리 지연시간** 급증 | 워크로드 특성에 맞춘 최적의 성능 포화 지점으로 큐 깊이 정밀 튜닝 | 극단적 응답 지연의 상위 백분위수 대폭 삭감 및 안정적 응답 보장 |
| 초고속 입출력 시 수백만 회의 인터럽트 폭증으로 코어 점유율 상승 | 운영체제 비동기 입출력 링 기반 **적응형 폴링** 모드 전환 적극 적용 | 잦은 인터럽트 문맥 교환 오버헤드 완벽 소거 및 코어 효율 극대화 |
| 호스트 코어와 제어기 연결 소켓 위치 불일치로 인한 원격 메모리 지연 | 큐 메모리 버퍼 및 인터럽트의 불균일 기억 장치 접근 친화성 하드 결속 | 원격 소켓 횡단 접근 지연 원천 차단 및 프로세서 데이터 지역성 확보 |
| 플래시 칩의 지속적인 고부하 쓰기 작업 시 칩 발열로 인한 열 스로틀링 유발 | 물리적 방열판 장착 구동 및 커널 차원의 입출력 횟수 평탄화 스케줄링 | 발열에 따른 컨트롤러의 급격한 성능 차단 및 대역폭 하락 현상 억제 |

#### 한줄 요약

- **적응형 폴링(io_uring)·인터럽트 병합·NUMA 바인딩·열 스로틀링 방어**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **NVMe-oF(NVMe over Fabrics)**: RDMA(RoCEv2, InfiniBand) 및 TCP/IP 네트워크 위에서 NVMe 프로토콜을 확장하여 원격 스토리지에 로컬 수준의 초저지연으로 접근하는 기술.

</details>

- 차세대 엔터프라이즈 스토리지 및 AI 데이터 파이프라인 구축 시 **PCIe 5.0 NVMe 및 io_uring 비동기 I/O 표준 채택**

#### 한줄 요약

- **다중 큐 스케일링과 비동기 폴링 튜닝**을 통한 스토리지 I/O 병목 제거
