## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비휘발성 메모리 익스프레스(Non-Volatile Memory Express)**: 고속 통신 버스 상에서 초고속 플래시 메모리의 병렬 입출력 처리 성능을 극대화하기 위해 다중 큐를 기반으로 설계된 호스트 컨트롤러 프로토콜이다.
- **피씨아이 익스프레스(PCIe)**: 고속 직렬 점대점 레인을 기반으로 프로세서와 차세대 입출력 장치를 연결하는 표준 확장 버스 규격이다.
- **솔리드 스테이트 드라이브(Solid-State Drive)**: 낸드 플래시 반도체를 고밀도로 배열하여 비휘발성 대용량 블록 입출력을 제공하는 대용량 저장장치이다.

</details>

- 정의: **피씨아이 익스프레스** 물리 레인 위에서 수만 개의 다중 큐와 병렬 명령 처리를 제공하는 **비휘발성 메모리 익스프레스** 저장 프로토콜
- 배경: 단일 명령 큐의 병목 지연이 극심했던 기존 인터페이스의 한계를 극복하고 멀티코어 프로세서의 초고속 병렬 입출력을 수용하기 위함

#### 한줄 요약

- 초고속 직렬 버스 위에서 다중 큐와 락리스 구조를 구동하여 저장장치의 데이터 입출력 병목을 완전히 소거하는 현대적인 저장 프로토콜이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **제출 큐(Submission Queue)**: 호스트가 블록 읽기 쓰기 명령 파이프라인 엔트리를 등록하고 배치하는 메모리 상의 원형 큐이다.
- **완료 큐(Completion Queue)**: 장치 제어기가 입출력 명령 수행을 완료한 뒤 그 상태 결과를 기록해 두는 메모리 상의 원형 큐이다.
- **도어벨 레지스터(Doorbell Register)**: 프로세서가 명령을 새로 적재했거나 큐 읽기를 마쳤음을 장치에 통지하기 위한 전용 메모리 맵 레지스터이다.
- **메시지 시그널 인터럽트 확장(MSI-X)**: 멀티코어 환경에서 완료 인터럽트를 핀 신호 없이 개별 코어로 분산시키는 메시지 기반 인터럽트 기술이다.

</details>

- 코어별 **제출 큐**와 **완료 큐** 매핑으로 공유 큐의 락 경합과 스레드 병목을 하드웨어적으로 감소함.
- **도어벨 레지스터** 통지와 직접 메모리 접근 방식을 결합하여 중앙처리장치의 입출력 파이프라인 지연을 극소화함.
- **메시지 시그널 인터럽트 확장** 벡터를 사용하여 완료 처리를 코어에 분산함으로써 높은 초당 입출력 횟수를 지원함.

#### 한줄 요약

- 코어별 전용 큐 할당과 레지스터 기반 통지, 그리고 메시지 기반 멀티코어 인터럽트를 통해 지연 없는 고동시성 입출력을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 드라이버(NVMe Host Driver)**: 운영체제 커널에서 블록 입출력 요청을 명령어로 변환하고 큐 메모리를 통제하는 커널 소프트웨어이다.
- **호스트 메모리 버퍼(Host Memory Buffer)**: 호스트 시스템 메모리 상에 직접 메모리 접근 주소로 할당되어 큐와 데이터 읽기 쓰기 버퍼를 보관하는 공간이다.
- **제어기(NVMe Controller)**: 저장장치 칩 내부에 탑재되어 물리 패킷 해독, 큐 인출 및 플래시 채널 병렬 입출력을 총괄하는 제어 실리콘 칩이다.

</details>

```text
[ 비휘발성 메모리 익스프레스 다중 큐 하드웨어 아키텍처 ]
+-------------------------------------------------------------+
| 호스트 다중 코어 프로세서 (코어 0 ~ 코어 N)                 |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 호스트 메모리 버퍼 (락리스 다중 큐 할당 영역)               |
|  ├─ 코어 0 : [ 제출 큐 0 ] ── [ 완료 큐 0 ]                 |
|  └─ 코어 N : [ 제출 큐 N ] ── [ 완료 큐 N ]                 |
+-------------------------------------------------------------+
                              │
[ 통지용 도어벨 레지스터 ] ── (피씨아이 익스프레스 초고속 레인)
                              │
+-------------------------------------------------------------+
| 장치 제어기 칩 (다중 채널 낸드 플래시 병렬 제어)            |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **제출 큐** 및 **완료 큐** | 호스트의 입출력 명령 엔트리 게시 및 장치의 작업 완료 상태 교환 제공 |
| **도어벨 레지스터** | 큐 꼬리 및 머리 포인터 변경 통지를 통한 호스트와 장치 간 직접 신호 전달 |
| 물리 레인 인터페이스 | 명령 및 데이터 패킷의 초고속 직접 메모리 접근 전송 물리 경로 제공 |
| **메시지 시그널 인터럽트 확장** | 다중 코어 아키텍처에 특화된 분산형 작업 완료 인터럽트 통보 처리 제공 |

#### 한줄 요약

- 호스트 메모리 상의 락리스 큐와 장치 레지스터가 직렬 버스로 묶여 다중 코어의 입출력 명령을 제어기로 끊임없이 쏟아낸다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **큐 포인터(Queue Pointer)**: 드라이버와 제어기가 원형 큐 배열 안에서 최신 명령 위치와 회수 위치를 가리키는 관리 인덱스이다.
- **플래시 채널(Flash Channel)**: 제어기가 복수의 낸드 플래시 칩으로 동시에 읽고 쓰기를 분산 수행하는 병렬 물리 데이터 통로이다.

</details>

```text
[ 호스트 응용 프로그램 입출력 요청 발생 ]
                      │
                      ▼
        [ 1. 제출 큐 명령 게시 및 기록 ]
                      │
                      ▼
        [ 2. 꼬리 포인터 도어벨 통지 ]
                      │
                      ▼
        [ 3. 장치 제어기 명령 DMA 인출 ]
                      │
                      ▼
        [ 4. 다중 채널 플래시 병렬 실행 ]
                      │
                      ▼
        [ 5. 메모리 데이터 및 완료 큐 기록 ]
                      │
                      ▼
        [ 6. 인터럽트 통보 및 큐 회수 갱신 ]
```

### 동작 원리

1. 제출 큐 명령 게시: 호스트 드라이버가 입출력 명령을 메모리 상의 **제출 큐**에 기록함.
2. 도어벨 통지: **도어벨 레지스터**에 꼬리 포인터를 갱신 기록하여 새 명령을 장치 제어기에 통지함.
3. 제어기 명령 인출: 제어기가 큐를 직접 메모리 접근으로 읽고 내부 플래시 변환 계층에 스케줄링 배치함.
4. 플래시 병렬 실행: 제어기가 하단의 다중 **플래시 채널**에서 물리적 낸드 읽기 쓰기를 병렬 처리함.
5. 데이터 및 큐 기록: 데이터를 호스트로 전송하고 **완료 큐**에 처리 상태를 기록함.
6. 인터럽트 및 큐 회수: 인터럽트로 호스트 코어에 완료를 알리고 호스트가 큐 헤드 포인터를 회수 갱신함.

#### 한줄 요약

- 명령 큐 기록, 도어벨 알림, 제어기 인출 및 플래시 병렬 실행을 거쳐 데이터를 전송하고 인터럽트로 완료를 회수하는 파이프라인이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고급 호스트 컨트롤러 인터페이스(AHCI)**: 구형 하드디스크 및 솔리드 스테이트 드라이브 전용 프로토콜로, 단일 큐 한계와 소프트웨어 락에 의한 병목이 극심했던 방식이다.
- **큐 깊이(Queue Depth)**: 단일 큐 내에 동시에 병렬 처리를 위해 대기열로 쌓아 둘 수 있는 최대 입출력 명령 묶음 개수이다.

</details>

| 비교 항목 | 비휘발성 메모리 익스프레스 (NVMe) | 고급 호스트 컨트롤러 인터페이스 (AHCI) |
|:---|:---|:---|
| 물리 버스 통신 규격 | 피씨아이 익스프레스 (PCIe) 기반의 초고속 대역폭 | 직렬 에이티에이 (SATA) 기반의 제한적 대역폭 |
| 지원 최대 입출력 큐 | 최대 65,535개의 다중 **제출 큐** 및 **완료 큐** | 단 1개의 입출력 명령 큐만 지원 |
| 최대 **큐 깊이** 지원 | 단일 큐당 최대 65,536개의 명령 엔트리 유지 가능 | 단일 큐당 최대 32개의 명령 엔트리로 극히 제한됨 |
| 인터럽트 처리 방식 | 코어 분산형 다중 메시지 시그널 인터럽트 적용 | 단일 코어 집중형 물리 핀 기반 인터럽트 적용 |
| 구조적 성능 확장성 | 다중 큐 및 다중 플래시 채널을 통한 높은 병렬 처리 보장 | 단일 큐 한계 및 단일 링크 제약으로 인해 입출력 병렬성 상실 |

#### 한줄 요약

- 최신 프로토콜은 버스 병렬 다중 큐를 기반으로 낸드 플래시의 잠재력을 폭발시키고, 구형 프로토콜은 단일 큐로 인해 성능을 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **인터럽트 병합(Interrupt Coalescing)**: 초당 수백만 번의 입출력 시 인터럽트 폭증을 막기 위해 완료 통보를 일정 시간이나 개수 단위로 묶어서 발송하는 기술이다.
- **적응형 폴링(Adaptive Polling)**: 하이엔드 저지연 환경에서 코어가 완료 큐 상태를 인터럽트 없이 100% 비동기적으로 폴링하여 문맥 교환을 원천 제거하는 기술이다.
- **꼬리 지연시간(Tail Latency)**: 전체 입출력 트랜잭션 중 가장 응답이 느린 상위 1%의 극단적인 지연시간 지표이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 큐 깊이를 과도하게 증가시킬 경우 큐 포화로 인한 **꼬리 지연시간** 급증 | 워크로드 특성에 맞춘 최적의 성능 포화 지점으로 큐 깊이 정밀 튜닝 | 극단적 응답 지연의 상위 백분위수 대폭 삭감 및 안정적 응답 보장 |
| 초고속 입출력 시 수백만 회의 인터럽트 폭증으로 코어 점유율 상승 | 운영체제 비동기 입출력 링 기반 **적응형 폴링** 모드 전환 적극 적용 | 잦은 인터럽트 문맥 교환 오버헤드 완벽 소거 및 코어 효율 극대화 |
| 호스트 코어와 제어기 연결 소켓 위치 불일치로 인한 원격 메모리 지연 | 큐 메모리 버퍼 및 인터럽트의 불균일 기억 장치 접근 친화성 하드 결속 | 원격 소켓 횡단 접근 지연 원천 차단 및 프로세서 데이터 지역성 확보 |
| 플래시 칩의 지속적인 고부하 쓰기 작업 시 칩 발열로 인한 열 스로틀링 유발 | 물리적 방열판 장착 구동 및 커널 차원의 입출력 횟수 평탄화 스케줄링 | 발열에 따른 컨트롤러의 급격한 성능 차단 및 대역폭 하락 현상 억제 |

#### 한줄 요약

- 큐 깊이 튜닝으로 꼬리 지연을 억제하고 적응형 폴링과 친화성 결속을 통해 인터럽트 오버헤드와 통신 지연을 은닉한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **인터페이스 최적화 기준(Interface Optimization Criteria)**: 대상 저장 시스템의 목표 입출력 횟수, 꼬리 지연시간 한계, 다중 코어 토폴로지를 분석하여 다중 큐 스케일링을 결정하는 가이드라인이다.

</details>

- 입출력 병렬성이 중요하면 **다중 큐 분산**, 극단적인 지연시간 통제가 중요하면 **적응형 폴링** 조정

#### 한줄 요약

- 필요한 초당 입출력 횟수와 지연 한계, 그리고 코어 소모 비용을 종합적으로 산정하여 큐의 개수와 통지 방식을 조율해야 한다.
