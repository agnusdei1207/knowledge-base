## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **비휘발성 메모리 익스프레스(Non-Volatile Memory Express, NVMe)**: PCIe SSD용 저지연 다중 큐 인터페이스이다.
- **주변 장치 상호 연결 익스프레스(Peripheral Component Interconnect Express, PCIe)**: 점대점 직렬 장치 인터커넥트이다.
- **솔리드 스테이트 드라이브(Solid-State Drive, SSD)**: 플래시 메모리 기반 저장장치이다.

</details>

- 정의/개념: PCIe SSD의 병렬 처리 능력을 다중 제출·완료 큐로 활용하는 **NVMe** 인터페이스이다.
- 배경/필요성: 레거시 SAS/SATA의 단일 명령 큐 규격(AHCI)은 멀티코어 환경의 동시성 요구와 낸드 플래시의 멀티채널 병렬성을 수용하지 못한다.

#### 한줄 요약

- NVMe는 코어별 제출·완료 큐와 PCIe 전송을 사용해 소프트웨어 경합을 줄이고 SSD의 채널 병렬성을 활용한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **제출 큐(Submission Queue, SQ)**: 호스트가 저장 명령을 게시하는 메모리 큐이다.
- **완료 큐(Completion Queue, CQ)**: 컨트롤러가 완료 정보를 기록하는 메모리 큐이다.
- **도어벨**: 새 큐 포인터를 알리는 MMIO 레지스터이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치가 CPU 복사 없이 메모리를 읽고 쓰는 방식이다.
- **메모리 매핑 입출력(Memory-Mapped Input/Output, MMIO)**: 메모리 주소로 장치 레지스터에 접근하는 방식이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 프로그램 명령을 실행하는 장치이다.
- **큐 깊이**: 큐에 동시에 대기시킬 수 있는 명령 수이다.
- **99번째 백분위 지연(99th Percentile Latency, p99 지연)**: 전체 요청의 99%가 이 값 이하에 완료되는 꼬리 지연 지표이다.

</details>

- 코어별 **다중 SQ•CQ 구성** 기반 잠금 경합을 축소한다.
- 명령 통지와 데이터 전송을 분리하는 **도어벨•DMA 구조**가 핵심이다.
- 큐 깊이 증가 시 포화 전에는 처리량이 증가하고, 포화 후에는 **p99 지연**이 증가한다.

#### 한줄 요약

- 큐 깊이를 늘리면 장치 포화 전에는 처리량이 증가하지만, 포화 후에는 대기 명령만 늘어 p99 지연이 증가한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **NVMe 호스트 드라이버**: 운영체제 I/O를 NVMe 명령으로 바꾸고 SQ•CQ를 관리하는 소프트웨어이다.
- **입출력(Input/Output, I/O)**: 호스트와 저장장치 사이의 데이터를 전달하는 경로이다.
- **호스트 메모리 큐•버퍼**: 명령•완료 상태와 읽기•쓰기 데이터를 직접 메모리 접근 방식으로 읽고 쓰도록 저장하는 영역이다.
- **NVMe 컨트롤러**: 큐 명령을 해석하고 플래시 채널에 병렬 실행하는 SSD 제어기이다.

</details>

```text
[NVMe 호스트 드라이버] -- [호스트 메모리 SQ·CQ·데이터 버퍼]
          |                              ⇅ DMA
          └─ MMIO 도어벨 ── [PCIe 링크] ── [NVMe 컨트롤러·SSD]
```

선의 의미: 호스트 드라이버가 메모리 큐를 공유하고 PCIe 링크가 해당 큐와 NVMe 컨트롤러•SSD를 잇는 정적 인터페이스 관계다.

| 구성요소 | 책임 |
|:---|:---|
| NVMe 호스트 드라이버 | 명령 변환•완료 회수 |
| 호스트 메모리 SQ·CQ·데이터 버퍼 | 명령·완료 상태와 전송 데이터 보관 |
| PCIe 링크 | 도어벨•명령•데이터 전송 |
| NVMe 컨트롤러·SSD | DMA·명령 해석과 플래시 병렬 처리 |

#### 한줄 요약

- 드라이버와 SSD는 호스트 메모리의 제출•완료 큐를 PCIe로 공유하며 비동기로 작업한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **큐 포인터**: 원형 큐에서 새 항목을 넣거나 회수할 위치를 나타내는 값이다.
- **메시지 신호 인터럽트 확장(Message Signaled Interrupts eXtended, MSI-X)**: 완료를 담당 중앙 처리 장치(Central Processing Unit, CPU)에 알리는 메시지 기반 인터럽트이다.
- **플래시 채널**: 솔리드 스테이트 드라이브(Solid-State Drive, SSD) 컨트롤러가 여러 플래시 메모리 묶음에 병렬 접근하는 독립 경로이다.
- **SQ 명령 게시**: 드라이버가 명령과 데이터 버퍼 주소를 제출 큐에 기록하는 단계이다.
- **도어벨 통지**: 새 SQ 꼬리 포인터를 MMIO 레지스터로 컨트롤러에 알리는 단계이다.
- **명령 DMA 조회**: NVMe 컨트롤러가 호스트 메모리의 새 SQ 엔트리를 DMA로 읽는 단계이다.
- **플래시 명령 실행**: 저장 명령을 여러 플래시 채널과 다이에 분산해 처리하는 단계이다.
- **데이터·완료 기록**: 데이터 버퍼와 CQ 엔트리를 DMA로 갱신하고 완료를 통지하는 단계이다.

</details>

```text
                       [호스트 I/O 요청]
                               |
                       1. SQ 명령 게시
                               |
                       2. 도어벨 통지
                               |
                     [NVMe 컨트롤러 기동]
                               |
                      3. 명령 DMA 조회
                               |
               +-------------------------------+
               | 병렬: 선택한 플래시 채널     |
               | 4. 플래시 명령 실행           |
               +-------------------------------+
                               |
                      5. 데이터•CQ DMA 기록
                               |
                     [MSI-X 완료 통지]
                               |
                     [CQ 회수•결과 반환]
```

### 동작 원리

1. **SQ 명령 게시**: 드라이버가 명령과 데이터 버퍼 주소를 호스트 메모리의 제출 큐에 기록한다.
2. **도어벨 통지**: MMIO 레지스터에 새 SQ **큐 포인터**를 기록해 컨트롤러에 명령 도착을 알린다.
3. **명령 DMA 조회**: NVMe 컨트롤러가 PCIe DMA로 새 제출 큐 엔트리를 읽어 실행을 준비한다.
4. **플래시 명령 실행**: 명령을 플래시 채널·다이에 분산해 읽기 또는 쓰기를 병렬 처리한다.
5. **데이터·완료 기록**: DMA로 호스트 데이터 버퍼와 CQ 엔트리를 갱신하고 MSI-X로 완료를 통지한다.

#### 한줄 요약

- 드라이버가 SQ에 명령을 게시하고 도어벨을 갱신하면, 컨트롤러는 DMA로 명령과 데이터를 처리한 뒤 CQ와 MSI-X로 완료를 알린다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **직렬 고급 기술 연결(Serial Advanced Technology Attachment, SATA)**: 전통적인 직렬 저장 인터페이스이다.
- **고급 호스트 제어기 인터페이스(Advanced Host Controller Interface, AHCI)**: 단일 명령 큐 중심 호스트 인터페이스이다.
- **다중 큐**: 중앙 처리 장치(Central Processing Unit, CPU) 코어나 워크로드별로 독립 제출 큐(Submission Queue, SQ)•완료 큐(Completion Queue, CQ)를 사용해 잠금 경합을 줄이는 구조이다.
- **직렬 레인**: 두 장치 사이의 한 쌍 송수신 경로로 여러 레인을 묶어 PCIe 대역폭을 늘리는 단위이다.
- **고동시성 입출력(High-Concurrency Input/Output, 고동시성 I/O)**: 많은 독립 저장 요청을 동시에 제출하고 완료할 수 있는 작업 특성이다.

</details>

| 저장 인터페이스 | NVMe•PCIe | SATA•AHCI |
|:---|:---|:---|
| 적용 기준 | **고동시성 I/O**에서 SSD 병렬성을 활용할 때 | 기존 운영체제·장치와의 SATA 호환성이 우선일 때 |
| 핵심 특징 | **다중 큐**와 PCIe 점대점 연결 | **AHCI**의 단일 명령 큐 |
| 한계 | PCIe 레인·발열과 큐 조정 복잡도 | 단일 큐 경합과 **SATA** 대역폭 한계 |

> 요약: 저지연•동시성은 **NVMe**, 호환성은 **AHCI**를 선택한다.

#### 한줄 요약

- 높은 동시성과 낮은 소프트웨어 지연에는 NVMe가 유리하고, 기존 SATA 장치 호환성이 우선이면 AHCI가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **인터럽트 병합**: 여러 완료 통지를 하나의 인터럽트로 묶는 최적화 기법이다.
- **적응형 폴링**: 부하에 따라 CQ 확인 방식을 바꾸는 최적화 기법이다.
- **비균등 메모리 접근(Non-Uniform Memory Access, NUMA)**: 노드별 메모리 지연이 다른 구조이다.
- **NUMA 친화도**: 큐•버퍼•CPU•SSD 경로를 같은 노드에 배치하는 정책이다.
- **열 스로틀링**: 온도 한도를 지키려고 SSD의 동작 속도를 낮추는 제어 동작이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장치 포화 후에도 큐 깊이를 늘려 **p99 지연** 증가 | 처리량·꼬리 지연 곡선으로 큐 깊이 상한 설정 | 불필요한 대기 감소로 꼬리 지연 완화 |
| 완료마다 인터럽트가 발생하거나 계속 폴링해 CPU 사용량 증가 | 부하에 따라 **인터럽트 병합·적응형 폴링** 전환 | 지연 목표를 지키며 CPU 처리 비용 제한 |
| 큐·버퍼·인터럽트 처리가 다른 노드에 있어 원격 NUMA 접근 | 큐 메모리와 **NUMA 친화도**를 같은 노드에 정렬 | 원격 메모리 왕복 제거로 I/O 지연 감소 |
| 지속 쓰기로 SSD 온도가 올라 **열 스로틀링** 발생 | 온도·대역폭 감시, 냉각과 쓰기 속도 제한 적용 | 온도 한도 내 지속 처리량 유지 |

> 사례: 큐•벡터•CPU를 같은 노드에 배치

#### 한줄 요약

- 큐·버퍼·인터럽트를 처리 코어와 같은 NUMA 노드에 배치하고 장치 포화점에 맞춰 큐 깊이를 제한하면 p99 지연을 낮출 수 있다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **큐 포화**: 장치 처리 능력보다 대기 명령이 많아 처리량은 늘지 않고 지연만 증가하는 상태이다.
- **NVMe 운용 기준**: 처리량·p99 지연·NUMA 배치를 함께 측정해 큐 구성과 깊이를 정하는 기준이다.

</details>

- **NVMe 운용 기준**에 따라 **고동시성 I/O**에는 **다중 큐**를 쓰고 **큐 포화** 시 큐 깊이를 축소한다.

#### 한줄 요약

- 다중 큐를 쓰되 큐 깊이와 NUMA 배치를 함께 조정해 처리량과 지연을 균형화한다.
