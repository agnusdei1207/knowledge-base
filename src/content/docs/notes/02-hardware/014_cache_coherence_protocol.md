## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 멀티코어 환경에서 복수 사설 캐시 사본 간의 쓰기 독점권과 최신 읽기 일관성을 유지하는 상태 전이 규약이다.
- **소유권(Ownership)**: 캐시 라인 데이터를 직접 수정할 수 있고 하위 메모리나 타 캐시에 최신 데이터를 제공할 책임을 갖는 독점 권한이다.
- **단일 작성자 불변식(Single-Writer Invariant)**: 특정 시점에 동일 메모리 주소를 수정할 수 있는 권한은 오직 단 하나의 코어만 보유한다는 원칙이다.

</details>

- 정의/개념: 멀티코어 환경에서 복수 사설 캐시에 복제된 데이터의 쓰기 독점권과 읽기 일치성을 상태 전이(State Transition)로 제어하는 하드웨어 프로토콜
- 배경/필요성: 동일 메모리 주소를 여러 코어가 동시 수정/참조할 때 발생하는 **데이터 비일관성(Stale Data Read) 오류 방지 및 전역 메모리 일관성 보장**

#### 한줄 요약

- **상태 전이(MESI/MOESI)** 기반 멀티코어 사설 캐시 간 쓰기 독점권과 최신 읽기 보장.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쓰기 직렬화(Write Serialization)**: 동일 주소에 대한 복수 쓰기 요청이 인터커넥트 중재를 통해 전역적으로 동일한 순서로 실행되도록 순서화하는 성질이다.
- **거짓 공유(False Sharing)**: 서로 다른 변수가 동일 라인에 위치하여 한 코어의 쓰기가 타 코어의 사본까지 무효화시키는 현상이다.

</details>

- **단일 작성자(Single Writer)** 및 **다중 독자(Multiple Readers)** 불변식 엄격 준수
- 모든 코어가 동일 주소 데이터 변경을 동일 순서로 관측하는 **쓰기 직렬화(Write Serialization)**
- 64바이트 캐시 라인 단위 일관성 관리로 인한 **거짓 공유(False Sharing) 오버헤드** 제어

#### 한줄 요약

- **단일 작성자·다중 독자 불변식**과 쓰기 직렬화 기반 전역 일관성 유지.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 캐시 라인에 2~3비트로 배치되어 M/E/S/I/O 일관성 상태를 표시하는 하드웨어 플래그이다.
- **일관성 제어기**: 로컬 코어의 Read/Write 요청과 버스 스누핑(Bus Snooping) 메시지를 처리하여 상태를 전이시키는 유닛이다.

</details>

```text
[ 캐시 일관성 제어기 구조 ]
+-----------------------------------------------------------+
| 캐시 라인 항목 : [유효 비트] [더티 비트] [상태 비트 (2~3bit)]|
| 상태 비트 구성 : 수정(M) / 소유(O) / 독점(E) / 공유(S) / 무효(I)|
+-----------------------------------------------------------+
| 일관성 제어기 (상태 전이 엔진)                            |
|  - 로컬 코어 요청 : Read, Write, Atomic                   |
|  - 원격 버스 요청 : BusRd, BusRdX (소유권 요청), BusUpgr  |
+-----------------------------------------------------------+
| 일관성 연결망 (스누핑 버스 / 디렉터리 크로스바 라우터)    |
+-----------------------------------------------------------+
```

선의 의미: 캐시 라인 상태 비트, 로컬/원격 요청을 처리하는 일관성 제어기 및 온칩 연결망 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 상태 비트 | 라인의 권한 및 변경 상태 표시 |
| 일관성 제어기 | 로컬 및 원격 요청에 따른 상태 전이 수행 |
| 일관성 연결망 | 통신 메시지 전달 및 제어권 중재 |
| 공유 메모리 계층 | 축출 더티 라인 수용 및 최종 상태 보존 |

#### 한줄 요약

- **상태 비트(M/E/S/I/O)** 기반 제어기와 일관성 인터커넥트 협업.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **MESI 상태**: Modified(수정/독점/더티), Exclusive(독점/클린), Shared(공유/클린), Invalid(무효)이다.
- **BusRdX**: 캐시 라인의 독점 쓰기 권한을 얻기 위해 타 캐시 사본의 무효화를 브로드캐스트하는 버스 트랜잭션이다.

</details>

```text
[ 로컬 코어 쓰기 요청 발생 (Store) ]
                 │
                 ▼
          [ 현재 상태 확인 ]
                 │
       ┌─────────┼─────────┐
       ▼         ▼         ▼
  [ Modified ] [ Exclusive ] [ Shared / Invalid ]
       │         │                 │
       │         │                 ▼
       │         │    [ 버스 BusRdX(무효화) 메시지 전송 ]
       │         │                 │
       │         │                 ▼
       │         │    [ 타 코어 사본 무효화 (Invalidate) ]
       │         │                 │
       ▼         ▼                 ▼
   [ 즉시 쓰기 ] [ Modified 전이 ] [ Modified 승격 후 쓰기 ]
```

**동작 원리**

1. **상태 확인**: 로컬 쓰기 요청 시 현재 캐시 라인의 상태(M, E, S, I) 확인
2. **소유권 요청**: Shared 또는 Invalid 상태일 경우 일관성 버스로 BusRdX(무효화 요청) 트랜잭션 발행
3. **타 코어 사본 무효화**: 버스를 스누핑하던 다른 모든 코어의 사본을 Invalid 상태로 강제 전이
4. **상태 승격 및 쓰기 완결**: 로컬 캐시 라인을 Modified 상태로 승격하고 쓰기 연산 완료

#### 한줄 요약

- 로컬 쓰기 시 **원격 사본 무효화(Invalidate) 후 Modified 상태로 승격** 기반 쓰기 완결.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Owned(O) 상태**: 수정된 더티 데이터를 메모리에 쓰지 않고도 타 코어와 공유할 수 있도록 쓰기 책임을 보존하는 MOESI 특유의 상태이다.

</details>

| 비교 항목 | MESI 프로토콜 (4-State) | MOESI 프로토콜 (5-State) |
|:---|:---|:---|
| 적용 기준 | 일반 멀티코어 프로세서 (Intel, ARM 표준) | 코어 간 데이터 공유 빈도가 높은 고성능 멀티프로세서 (AMD) |
| 핵심 특징 | Modified, Exclusive, Shared, Invalid 4상태 | Owned(O) 상태 추가로 메모리 기록 없는 더티 공유(Dirty Sharing) |
| 한계 및 위험 | 공유 사본 요청 시 메모리 라이트백 발생으로 대역폭 소모 | 5개 상태 전이 제어 회로의 하드웨어 복잡도 및 검증 비용 증가 |

#### 한줄 요약

- MESI는 **단순 4상태 제어**, MOESI는 **Owned 상태 기반 더티 공유로 메모리 트래픽 절감**.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Cache-to-Cache Transfer(C2C)**: 메모리까지 가지 않고 데이터 라인을 가진 다른 코어 캐시에서 직접 데이터를 복사해오는 고속 전송이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복수 코어의 교차 쓰기로 소유권 핑퐁 및 트래픽 폭증 | 스레드 스케줄링 **소유권 지역화** 설정 적용 | 불필요한 무효화 통신 트래픽의 파괴적 절감 |
| 데이터 공유 요청 시 매번 메모리 기록으로 인한 지연 발생 | MOESI 프로토콜 채택 및 **캐시 간 전달** 인프라 연동 | 메모리 쓰기 억제 및 데이터 공유 지연시간 극소화 |
| 독립 변수가 동일 라인에 겹쳐 발생하는 잦은 거짓 공유 | 자료구조 선언 시 캐시 라인 패딩 최적화 연동 | 구조체 패딩을 통한 불필요한 라인 무효화 방어 |
| 동시 접근 시 상태 전이 오류로 인한 **프로토콜 불변식** 위반 | 정형 검증을 통한 상태 머신 코너케이스 스트레스 테스트 | 멀티코어 메모리 오염 및 데이터 경합 원천 차단 |

#### 한줄 요약

- **소유권 지역화·캐시 간 전달(C2C)·캐시 라인 패딩** 기반 핑퐁 트래픽 방어.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **디렉터리 기반 프로토콜(Directory-based Coherence)**: 코어 수가 수십~수백 개로 증가할 때 버스 브로드캐스트의 한계를 극복하기 위해 중앙/분산 디렉터리로 공유자 목록을 추적하는 대규모 일관성 아키텍처이다.

</details>

- 데이터 공유 빈도 및 온칩 대역폭 분석 기반 **MESI/MOESI 프로토콜 선택 및 캐시 간 전송(C2C) 최적화**

#### 한줄 요약

- **공유 트래픽과 하드웨어 복잡도** 절충 기반 최적 일관성 프로토콜 구현.
