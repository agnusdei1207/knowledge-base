## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 멀티코어 프로세서의 개별 사설 캐시에 복제된 동일 주소 데이터 사본들이 상호 불일치하지 않도록 하드웨어 상태 머신과 버스 트랜잭션을 통해 정합성을 보장하는 통신 규약.
- **소유권(Ownership)**: 특정 캐시 라인을 독점적으로 수정할 수 있는 권한이자, 타 코어의 읽기/쓰기 요청 시 메모리 대신 최신 데이터를 직접 공급(Supply)해야 하는 하드웨어 책임.
- **단일 작성자·다중 독자 불변식(Single-Writer-Multiple-Reader, SWMR)**: 임의의 시점에 특정 메모리 주소에 대해 단 하나의 코어만 쓰기 권한을 갖거나, 다수의 코어가 읽기 전용 사본만을 공유하도록 강제하는 일관성의 핵심 불변식.
- **오래된 값(Stale Data)**: 타 코어에 의해 주기억장치나 캐시 원본이 갱신되었으나 무효화되지 않아 사설 캐시에 잔존하는 비정합적 데이터.

</details>

- 정의/개념: 멀티코어의 사설 캐시들이 동일 메모리 주소를 복제할 때 **단일 작성자·다중 독자(SWMR)** 원칙을 하드웨어 상태 전이로 강제하는 **캐시 일관성 프로토콜(MESI/MOESI)**
- 배경/필요성: 사설 캐시 간 동기화 기제 없이는 **타 코어의 데이터 수정이 다른 코어에 전파되지 않아 오래된 값(Stale Data) 참조 오류 불가피**

#### 한줄 요약
- 멀티코어 환경에서 사설 캐시 간 데이터 불일치를 방지하기 위해 하드웨어 상태 전이로 단일 주소에 대한 사본 정합성을 유지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **메모리 배리어(Memory Barrier / Fence)**: 비순차적 명령어 실행(OoO) 및 스토어 버퍼로 인해 발생하는 서로 다른 메모리 주소 간의 읽기/쓰기 실행 순서 역전을 방지하는 하드웨어 펜스 명령어.
- **락(Lock / Mutex)**: `Read-Modify-Write` 복합 연산 구간에 대해 한 번에 하나의 스레드만 진입하도록 상호 배제(Mutual Exclusion)를 보장하는 소프트웨어 동기화 기법.
- **무효화 기반 프로토콜(Write-Invalidate)**: 특정 코어가 캐시 블록을 수정하기 전에 버스를 통해 다른 모든 캐시의 동일 사본을 무효화(Invalid)시켜 단독 소유권을 확보하는 방식.

</details>

- 단일 주소 사본 일치 (캐시 일관성 계층): **SWMR** 및 쓰기 직렬화를 통해 단일 메모리 주소에 대한 모든 캐시 사본 간 최신값 정합성을 하드웨어가 100% 보장
- 다중 주소 간 순서 제어 (메모리 모델 계층): 캐시 일관성은 단일 주소만 다루므로, 서로 다른 주소 간 비순차적 실행(OoO) 재정렬은 **메모리 배리어(Fence)** 명령어로 제어
- 임계 구역 원자성 보장 (소프트웨어 락 계층): 캐시 일관성이 유지되어도 복합 연산 동시성 경합은 방지할 수 없으므로 **락(Lock/Mutex)** 및 원자적 명령어(CAS)로 상호 배제 보장

#### 한줄 요약
- 캐시 일관성은 단일 주소 사본을, 메모리 배리어는 주소 간 실행 순서를, 락은 임계 구역의 복합 연산 원자성을 각각 분담한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 각 캐시 라인마다 2~3비트로 할당되어 현재 블록의 일관성 상태(M, E, S, I, O 등)를 기록하는 제어 필드.
- **캐시 제어기(Cache Controller)**: 로컬 CPU 코어의 요청과 인터커넥트에서 수신되는 타 코어의 스누핑 요청을 감지하여 캐시 상태를 전이시키는 하드웨어 로직.
- **스누프 필터(Snoop Filter)**: 사설 캐시가 보유한 라인 목록을 중앙에서 추적하여 사본이 없는 코어로의 불필요한 스누프 브로드캐스트를 차단하는 하드웨어 유닛.

</details>

```text
[멀티코어 캐시 일관성 하드웨어 아키텍처]
 ├─ [코어 0 사설 캐시] ── [캐시 라인 (Tag | Data | 상태비트: M/E/S/I/O)] ── [캐시 제어기] ─┐
 ├─ [코어 1 사설 캐시] ── [캐시 라인 (Tag | Data | 상태비트: M/E/S/I/O)] ── [캐시 제어기] ─┤
 │         ···                                                                             ├─► [온칩 일관성 인터커넥트 (Snoop Bus / Mesh)]
 └─ [코어 N 사설 캐시] ── [캐시 라인 (Tag | Data | 상태비트: M/E/S/I/O)] ── [캐시 제어기] ─┘        │
                                                                                                   ▼
                                                                                   [스누프 필터 / 디렉터리 제어기]
                                                                                                   │
                                                                                                   ▼
                                                                                   [공유 LLC (L3) 및 주기억장치]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 캐시 제어기는 로컬 CPU와 원격 인터커넥트의 트랜잭션을 동시에 감시함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **상태 비트 (State Bits)**| 캐시 라인 헤더 | 현재 라인의 일관성 상태(M, E, S, I, O) 표시 | 2~3비트 하드웨어 플래그 |
| **캐시 제어기** | 각 코어 캐시 | 로컬 읽기/쓰기 처리 및 원격 스누프 감시/상태 전이 | 1클록 내 스누프 응답 |
| **일관성 인터커넥트** | 온칩 네트워크 | BusRd, BusRdX, BusUpgr 등 일관성 트랜잭션 전파 | Snooping Bus 또는 2D Mesh |
| **스누프 필터/디렉터리**| LLC/메모리 경계 | 사본 보유 코어를 필터링하여 불필요한 브로드캐스트 억제 | 대규모 코어 확장성 보장 |

#### 한줄 요약
- 캐시 일관성 시스템은 라인별 상태 비트, 캐시 제어기, 온칩 인터커넥트, 스누프 필터가 유기적으로 맞물려 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 라인이 단독 수정되어 메모리와 불일치(Dirty)하며, 축출 시 메모리 되쓰기 책임이 있는 상태.
- **독점(Exclusive, E)**: 단일 캐시만 사본을 보유하고 메모리와 일치(Clean)하여, 버스 트랜잭션 없이 즉시 쓸 수 있는 상태.
- **공유(Shared, S)**: 복수의 캐시가 동일한 클린 사본을 공유하며, 읽기만 가능하고 쓰기 시 무효화가 선행되어야 하는 상태.
- **무효(Invalid, I)**: 유효한 데이터가 없거나 타 코어의 쓰기로 사본이 무효화된 상태.
- **BusRdX / BusUpgr**: 쓰기 권한 획득을 위해 타 캐시 사본을 모두 무효화(Invalidate)시키는 버스 트랜잭션.

</details>

```text
[ 로컬 코어의 동작 요청 ]
 ├─ [ 로컬 읽기 (Read Miss) ]
 │    └─ BusRd 발행 ➔ 타 캐시 사본 있음: S 상태 전이 / 타 캐시 사본 없음: E 상태 전이
 │
 └─ [ 로컬 쓰기 (Write Request) ]
      ├─ I 상태에서 쓰기: BusRdX 발행 ➔ 타 캐시 모두 무효화(I) ➔ M 상태 전이 후 쓰기
      ├─ S 상태에서 쓰기: BusUpgr 발행 ➔ 타 캐시 모두 무효화(I) ➔ M 상태 승격 후 쓰기
      ├─ E 상태에서 쓰기: 버스 트랜잭션 없이 ➔ M 상태로 1클록 즉시 승격 후 쓰기
      └─ M 상태에서 쓰기: 0 지연으로 로컬 캐시 즉시 쓰기 완료

[ 원격 스누프 수신 동작 ]
 ├─ BusRd 수신: M 보유 시 데이터 공급 후 S 전이 / E·S 보유 시 S 상태 유지
 └─ BusRdX/BusUpgr 수신: M·E·S 보유 시 즉시 I(Invalid)로 무효화 전이
```

분기 결과: **E 상태 쓰기는** 버스 트랜잭션 없이 즉시 완료되고, **S/I 상태 쓰기는** BusRdX/BusUpgr를 통해 타 코어를 무효화한 후 쓰기를 완결함

#### 한줄 요약
- MESI 프로토콜은 로컬 요청과 원격 스누프 신호에 따라 M, E, S, I 4개 상태를 상호 전이시키며 SWMR 불변식을 유지한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: MOESI에서 메모리에 되쓰지 않은 더티 사본을 보유한 채 타 캐시와 공유를 허용하며, 데이터 응답 책임을 독점하는 상태.
- **전달(Forward, F)**: MESIF에서 다수의 클린 공유 사본 중 단 1개 라인만 데이터 응답 책임을 전담하는 상태.

</details>

| 비교 항목 | MESI 프로토콜 | MESIF 프로토콜 (Intel) | MOESI 프로토콜 (AMD) |
|:---|:---|:---|:---|
| 상태 구성 | **M, E, S, I (4가지 기본 상태)** | **M, E, S, I + F (Forward)** | **M, E, S, I + O (Owned)** |
| 핵심 차별점 | 표준 무효화 기반 일관성 프로토콜 | **클린 공유 사본 중 1개만 응답자(F)로 지정** | **더티 데이터를 메모리에 안 쓰고 코어 간 직접 공유(O)** |
| 장점 | 구조 단순, 하드웨어 비용 최소 | 대규모 공유 시 중복 응답 대역폭 낭비 제거 | 더티 라인 공유 시 DRAM 되쓰기 트래픽 대폭 절감 |
| 한계 | 더티 데이터 공유 시 메모리 되쓰기 지연 | F 상태 이전 로직 추가 | O 상태 보유 코어의 응답 부담 집중 |

#### 한줄 요약
- 기본은 MESI이며, 클린 공유 트래픽 절감에는 MESIF(Forward), 더티 데이터 공유 지연 절감에는 MOESI(Owned)가 최적화된 확장이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 독립된 변수를 갱신하지만 동일한 64B 캐시 라인에 위치하여 불필요한 무효화가 반복되는 현상.
- **캐시 라인 핑퐁(Cache Line Ping-Ponging)**: 여러 코어가 동일 캐시 라인을 번갈아 수정하여 소유권이 코어 간을 지속 왕복하는 병목 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수가 한 라인에 묶여 **거짓 공유** 및 **캐시 라인 핑퐁** 발생 | **캐시 라인 패딩(64B Align)** 및 스레드별 로컬 변수화 | 불필요한 일관성 무효화 트래픽 및 버스 정체 제거 |
| 코어 수 증가에 따른 스누프 브로드캐스트 트래픽 포화 | **스누프 필터(Snoop Filter) 및 디렉터리 기반 일관성** 전환 | 사본 보유 노드에만 선택적 통지하여 확장성 보장 |
| 더티 데이터 공유 시 DRAM 왕복 지연 발생 | **MOESI 프로토콜 및 캐시 간 직접 전송(Intervention)** 채택 | 메인 메모리 접근 생략으로 데이터 공급 지연 50% 단축 |

#### 한줄 요약
- 캐시 일관성 실무 최적화는 거짓 공유 방지를 위한 64B 패딩, 스누프 필터 기반 브로드캐스트 억제, MOESI 캐시 간 직접 전송으로 완성된다.

## Ⅶ. 결론

- 멀티코어 시스템의 데이터 정합성을 보장하기 위해 **기본 사설 캐시 계층에는 MESI/MOESI 무효화 기반 일관성 프로토콜을 필수 구현**하고, 비순차 실행에 따른 주소 간 순서 역전은 **메모리 배리어(Memory Barrier)**로 통제하며, 임계 구역 동시성 경합은 **소프트웨어 락(Lock)**으로 격리하는 하드웨어-소프트웨어 계층화 동기화 아키텍처 확립

#### 한줄 요약
- 캐시 일관성은 단일 주소 정합성을 보장하는 하드웨어 기초이며, 메모리 배리어와 락이 결합되어 완전한 동시성 시스템을 완성한다.
