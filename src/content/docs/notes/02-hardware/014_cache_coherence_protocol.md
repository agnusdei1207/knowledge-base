## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 여러 사설 캐시에 흩어진 같은 주소의 사본을 상태 비트로 추적하고, 쓰기 권한을 한 캐시에 몰아준 뒤 나머지를 무효화하는 방식으로 사본 간 불일치를 차단하는 하드웨어 규약.
- **소유권(Ownership)**: 특정 캐시 라인을 수정할 수 있고, 다른 캐시의 요청에 최신 값을 대신 응답할 책임까지 지는 권한.
- **단일 작성자·다중 독자 불변식(Single-Writer-Multiple-Reader, SWMR)**: 어느 시점에도 한 주소에 대해 작성자 한 캐시만 존재하거나, 작성자 없이 독자 여러 캐시만 존재하도록 강제하는 원칙.
- **오래된 값(Stale Data)**: 다른 코어가 이미 갱신했는데도 무효화가 닿지 않아 사본에 남아 있는 이전 값으로, 읽어도 오류가 나지 않고 조용히 잘못된 결과만 내놓는 것이 위험 요소.

</details>

- 정의/개념: 멀티코어의 사설 캐시가 같은 주소를 복제할 때 **SWMR**을 상태 전이로 강제해 사본 정합성을 지키는 하드웨어 동기화 규약
- 배경/필요성: 코어별 사설 캐시는 성능을 위해 사본을 만들지만, 한 코어의 갱신이 다른 사본에 전파되지 않으면 **오래된 값** 읽기가 발생

#### 한줄 요약
- 사설 캐시는 성능을 위해 사본을 늘리고 일관성 프로토콜은 그 사본을 다시 줄이므로, 두 힘의 균형점이 곧 멀티코어 성능의 상한이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 값 불변식(Data-Value Invariant)**: 작성자가 없는 구간에서 모든 사본의 값이 마지막 작성자가 남긴 값과 같아야 한다는 조건으로, SWMR이 지키지 못하는 값 자체의 정확성을 보완.
- **메모리 일관성 모델(Memory Consistency Model)**: 서로 다른 주소에 대한 접근이 다른 코어에게 어떤 순서로 보이는지를 규정하는 상위 계약으로, 순차 일관성•TSO 등으로 구분.
- **무효화 기반 프로토콜(Write-Invalidate)**: 쓰기 전에 타 캐시 사본을 모두 버리게 해 작성자를 하나로 만드는 방식으로, 상용 프로세서가 채택하는 주류.
- **갱신 기반 프로토콜(Write-Update)**: 쓴 값을 타 캐시 사본에 그대로 전파하는 방식으로, 사본을 살려 두는 대신 쓰기마다 대역폭을 소모.

</details>

- **SWMR**과 **데이터 값 불변식**을 함께 만족해야 일관성이 성립하며, 상태 전이는 두 조건을 하드웨어로 구현한 결과
- 일관성은 단일 주소의 사본 정합성만 책임지고, 서로 다른 주소 간 관찰 순서는 **메모리 일관성 모델**이 담당하는 별개 계층
- 상용 프로세서는 쓰기마다 대역폭을 쓰는 **갱신 기반 프로토콜** 대신 사본을 버리는 **무효화 기반 프로토콜**을 채택

#### 한줄 요약
- 일관성 프로토콜은 한 주소의 사본만 책임지므로, 락•배리어가 필요한 이유는 일관성이 부족해서가 아니라 애초에 다른 계층의 문제이기 때문이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 캐시 라인마다 붙어 현재 사본이 수정 가능한지•읽기만 가능한지•사용 불가인지를 표시하며, 프로토콜의 전이 판단 입력이 되는 제어 비트.
- **캐시 제어기(Cache Controller)**: 자기 코어의 요청을 처리하는 경로와 인터커넥트에서 들어온 타 코어 요청에 응답하는 경로를 함께 수행해 상태를 전이시키는 회로.
- **스누프 필터(Snoop Filter)**: 어느 캐시가 어떤 라인을 보유하는지 요약해 두고 사본이 없는 캐시에는 스누프 요청을 보내지 않도록 걸러 내는 구조.
- **디렉터리(Directory)**: 라인별 공유자 목록과 상태를 중앙에 유지해 브로드캐스트 대신 해당 공유자에게만 메시지를 보내도록 하는 구조.

</details>

```text
[캐시 일관성 하드웨어]
├─ 코어별 사설 캐시
│  └─ 캐시 라인
│     ├─ 태그
│     ├─ 데이터 블록
│     └─ 상태 비트 (M·E·S·I / +O / +F)
├─ 캐시 제어기
│  ├─ 로컬 요청 처리 경로
│  └─ 스누프 응답 경로
├─ 일관성 인터커넥트 (버스·링·메시)
├─ 스누프 필터 또는 디렉터리
└─ 공유 LLC·주기억장치
```

선의 의미: 가지(`├─`)는 소유 관계이며, 캐시 제어기의 두 경로는 로컬 요청과 원격 요청을 각각 담당

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 태그·데이터·**상태 비트**를 한 단위로 묶어 **소유권** 보관 |
| 상태 비트 | 사본의 수정·읽기·무효 권한 표시 및 전이 판단 입력 제공 |
| 캐시 제어기 | 로컬 요청 발행과 원격 스누프 응답을 수행해 상태 전이 실행 |
| 일관성 인터커넥트 | 요청·무효화·데이터 응답 메시지를 코어 간 전달 |
| **스누프 필터**·**디렉터리** | 사본 보유 위치를 추적해 불필요한 메시지 수신자 제거 |
| 공유 LLC·주기억장치 | 최종 값 보관 및 어느 캐시도 사본이 없을 때 응답 |

#### 한줄 요약
- 상태 비트는 라인마다 몇 비트에 불과하지만 그 비트를 코어 전체에 걸쳐 모순 없이 유지하는 비용이 일관성 하드웨어 대부분을 차지한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 이 캐시만 사본을 가지고 값도 메모리와 달라, 자유롭게 쓸 수 있는 대신 축출 시 되쓰기 의무를 지는 상태.
- **독점(Exclusive, E)**: 이 캐시만 사본을 가지지만 값은 메모리와 같아, 버스 요청 없이 곧바로 M으로 전이해 쓸 수 있는 상태.
- **공유(Shared, S)**: 다른 캐시도 같은 클린 사본을 가질 수 있어 읽기만 허용되고, 쓰려면 타 사본 무효화가 선행돼야 하는 상태.
- **무효(Invalid, I)**: 사본이 없거나 무효화돼 어떤 접근도 미스로 처리되는 상태.
- **버스 트랜잭션(Bus Transaction)**: 읽기 사본을 요청하는 BusRd, 쓰기 권한까지 요청하는 BusRdX, 이미 보유한 S 사본의 권한만 올리는 BusUpgr로 구분되는 일관성 요청.

</details>

```text
캐시 접근 요청
     │
┌────┴─────┐
로컬 요청   원격 스누프 수신
│              │
├ 읽기·I → BusRd 발행         ├ BusRd 수신
│  ├ 타 사본 있음 → S         │  ├ M 보유 → 데이터 전달 후 S
│  └ 타 사본 없음 → E         │  └ E·S 보유 → S 유지
│                             │
├ 쓰기·I → BusRdX 발행 → M    └ BusRdX·BusUpgr 수신
├ 쓰기·S → BusUpgr 발행 → M      └ M·E·S 보유 → I 무효화
├ 쓰기·E → 버스 트랜잭션 없이 M
└ 쓰기·M → M 유지
```

분기 결과: 로컬 쓰기는 사본을 이미 독점했는지에 따라 **버스 트랜잭션** 발생 여부가 갈리고, 원격 스누프는 요청 종류에 따라 사본을 넘기거나 버림

#### 한줄 요약
- E 상태가 존재하는 이유는 공유되지 않는 데이터를 읽고 곧바로 쓰는 흔한 패턴에서 버스 트랜잭션 한 번을 통째로 없애기 위함이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: 메모리에 되쓰지 않은 더티 값을 계속 보유하면서 다른 캐시에는 S 사본 배포를 허용하고, 이후 요청의 응답 책임까지 떠안는 상태.
- **전달(Forward, F)**: 여러 클린 공유 사본 가운데 응답 담당을 하나로 지정해 중복 응답을 없애는 상태.
- **개입 전송(Intervention)**: 메모리 대신 최신 사본을 보유한 캐시가 요청자에게 직접 데이터를 건네 왕복 지연을 줄이는 동작.
- **MESI**: M·E·S·I 네 상태만으로 단독 수정과 클린 공유를 구분하는 무효화 기반 프로토콜의 기본형.
- **MESIF**: MESI에 F를 더해 클린 공유자 가운데 응답 담당 하나를 지정함으로써 중복 개입 전송을 없앤 인텔 계열 프로토콜.
- **MOESI**: MESI에 O를 더해 더티 값을 메모리에 되쓰지 않은 채 공유할 수 있게 한 AMD 계열 프로토콜.

</details>

| 일관성 프로토콜 | MESI | MESIF | MOESI |
|:---|:---|:---|:---|
| 적용 기준 | 상태 수를 늘리지 않고 **SWMR**만 확실히 지키면 되는 경우 | 클린 공유 사본이 많아 **개입 전송** 중복 응답이 문제인 경우 | 더티 값 공유가 잦아 되쓰기 트래픽이 병목인 경우 |
| 핵심 특징 | M·E·S·I 4상태로 단독 수정과 클린 공유를 구분 | **전달(Forward, F)**로 클린 공유자 중 응답자를 단일 지정 | **소유(Owned, O)**로 더티 값을 되쓰지 않은 채 공유 허용 |
| 한계 | 더티 값 공유 시 메모리 되쓰기를 거쳐야 함 | 더티 값 공유는 여전히 되쓰기 필요 | 상태·메시지 조합 증가로 검증 부담 상승 |

#### 한줄 요약
- 세 프로토콜의 추가 상태는 모두 응답 책임을 누구에게 지울지를 정하는 장치이며, 상태를 늘린 만큼 검증해야 할 전이 조합도 함께 늘어난다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **일관성 미스(Coherence Miss)**: 용량•충돌이 아니라 타 코어의 무효화 때문에 발생하는 미스로, 캐시를 키워도 줄지 않는 것이 특징.
- **거짓 공유(False Sharing)**: 서로 다른 변수가 우연히 한 캐시 라인에 배치돼 실제로는 독립적인 갱신인데도 무효화가 오가는 현상.
- **캐시 라인 핑퐁(Cache Line Ping-Ponging)**: 같은 라인의 소유권이 코어 사이를 반복해 오가며 매 접근이 미스로 바뀌는 상태.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립적으로 갱신되는 변수 사이에 여유 공간을 넣어 서로 다른 라인에 배치되도록 만드는 기법.
- **정형 검증(Formal Verification)**: 도달 가능한 모든 상태 전이 조합을 탐색해 불변식 위반 여부를 수학적으로 확인하는 검증 방법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수가 한 라인에 묶여 **거짓 공유**로 **캐시 라인 핑퐁** 발생 | **캐시 라인 패딩**·코어별 지역 변수 분리 후 최종 합산 | 캐시 크기로 못 줄이는 **일관성 미스** 제거 |
| 더티 사본 요청이 메모리 되쓰기를 거쳐 지연 | **개입 전송** 활용·데이터를 갱신 코어 근처에 배치 | 최신 값 전달 경로 단축 |
| 코어 수 증가로 스누프 브로드캐스트가 인터커넥트 포화 | **스누프 필터** 도입·**디렉터리** 기반으로 전환 | 메시지 수신자를 실제 공유자로 한정해 확장성 확보 |
| 동시 요청 경합 구간에서 전이 누락으로 **SWMR** 위반 | 과도 상태 명시·**정형 검증**과 상태 머신 자동 시험 | 재현 어려운 일관성 버그를 설계 단계에서 차단 |

#### 한줄 요약
- 일관성 비용은 프로토콜 선택이 아니라 데이터 배치가 결정하므로, 어떤 변수를 어느 코어가 쓰는지를 먼저 정리해야 하드웨어 최적화가 효과를 낸다.

## Ⅶ. 결론

- 코어 수가 적고 공유가 드물면 **MESI**, 더티 값 공유가 잦으면 **MOESI**, 클린 공유 사본이 많으면 **MESIF**를 택하되, 코어 수가 커지면 상태 추가보다 **디렉터리** 전환으로 메시지 범위를 좁히는 것이 우선

#### 한줄 요약
- 상태를 늘리는 선택은 공유 패턴이 무엇인지에 답하고, 디렉터리로 옮기는 선택은 코어가 몇 개인지에 답하므로 두 결정은 서로를 대체하지 못한다.
