## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 여러 사설 캐시에 복제된 데이터의 쓰기 권한과 최신 읽기 값을 상태 전이로 관리하는 규약.
- **소유권(Ownership)**: 특정 캐시 라인을 수정하거나 최신 데이터를 제공할 수 있는 권한과 책임.
- **단일 작성자 불변식(Single-Writer Invariant)**: 동일 메모리 위치를 수정할 수 있는 권한은 한 시점에 하나의 코어만 가진다는 원칙.

</details>

- 정의/개념: 멀티코어 환경에서 사설 캐시 간 **상태 전이 메커니즘**을 통해 데이터 정합성을 유지하는 하드웨어 동기화 프로토콜
- 배경/필요성: 사설 캐시에 같은 주소의 사본이 복제되면 갱신 후 다른 코어가 **오래된 값**을 읽을 수 있음

#### 한줄 요약
- 여러 코어가 같은 데이터를 복사해 보관할 때 한 코어만 수정권을 갖고 나머지는 최신본을 읽게 정하는 약속이 캐시 일관성 프로토콜이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다중 독자(Multiple Readers)**: 수정 권한이 없는 여러 캐시가 같은 클린 데이터를 동시에 읽는 상태.
- **쓰기 직렬화(Write Serialization)**: 같은 주소의 여러 쓰기 요청을 모든 코어가 동일한 순서로 관찰하게 하는 성질.
- **거짓 공유(False Sharing)**: 서로 다른 변수가 한 캐시 라인에 배치돼 독립 갱신인데도 무효화 트래픽이 발생하는 현상.

</details>

- **단일 작성자 불변식**으로 한 시점에 하나의 코어만 수정 허용
- **쓰기 직렬화**를 통해 모든 코어가 동일한 쓰기 순서를 관찰하도록 보장
- 라인 단위 공유에서 **거짓 공유** 발생 시 불필요한 무효화 인터커넥트 트래픽 증가

#### 한줄 요약
- 일관성은 같은 값을 읽게 하는 것뿐 아니라, 누가 먼저 썼는지를 모두가 같은 순서로 보게 해 프로그램이 예측 가능하도록 만드는 규칙이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 캐시 라인의 수정·공유·무효 상태를 나타내는 제어 비트.
- **일관성 제어기(Coherence Controller)**: 로컬 요청과 원격 일관성 메시지에 따라 캐시 라인 상태를 전이시키는 회로.
- **일관성 인터커넥트(Coherence Interconnect)**: 일관성 요청·응답·데이터를 코어 간 전달하는 온칩 연결망.

</details>

```text
[캐시 일관성 구성]
├─ 캐시 라인
│  ├─ 데이터
│  └─ 상태 비트 (M·E·S·I 또는 M·O·E·S·I)
├─ 일관성 제어기
├─ 일관성 인터커넥트
└─ 공유 메모리 계층
```

선의 의미: 가지(`├─`)는 소유 관계; 일관성 제어기와 인터커넥트는 모든 코어의 캐시를 조정

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 데이터와 **소유권** 상태 보관 |
| 상태 비트 | 수정·공유·무효 권한 표시 |
| 일관성 제어기 | 로컬·원격 요청별 **상태 전이** |
| 일관성 인터커넥트 | 무효화·소유권·데이터 메시지 코어 간 전달 |
| 공유 메모리 계층 | 최종 데이터 보관·캐시 미스 응답 |

#### 한줄 요약
- 각 캐시는 데이터 옆에 현재 권한을 상태 비트로 표시하고, 제어기와 인터커넥트가 그 권한을 다른 코어와 조정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 한 캐시만 최신 더티 데이터를 보유하고 수정할 수 있는 MESI 상태.
- **독점(Exclusive, E)**: 한 캐시만 클린 데이터를 보유하며 로컬 쓰기로 M 전이 가능한 MESI 상태.
- **공유(Shared, S)**: 여러 캐시가 같은 클린 데이터를 읽기 전용으로 보유하는 MESI 상태.
- **무효(Invalid, I)**: 캐시 라인이 없거나 사용 불가 상태인 MESI 상태.

</details>

```text
로컬 쓰기 요청
      │
      ▼
MESI 상태 확인
      │
 ┌────┼──────────────┐
 │    │              │
M·E   S              I
 │    │              │
 │    2. 공유 라인 소유권 획득
 │      └─ 타 코어 S 사본 무효화
 │              │
1. 단독 라인 로컬 갱신      3. 무효 라인 반입·소유권 획득
 └────┬──────────────┘
      │
    M 상태로 갱신
```

**동작 원리**

1. **단독 라인 로컬 갱신**: M은 상태를 유지하고 E는 M으로 전이하며 데이터 수정
2. **공유 라인 소유권 획득**: 타 코어의 S 사본을 무효화한 뒤 M으로 전이
3. **무효 라인 반입·소유권 획득**: 최신 데이터를 수신하고 배타적 쓰기 권한 확보

#### 한줄 요약
- 이미 혼자 가진 데이터면 바로 쓰고, 다른 코어와 공유한 데이터면 먼저 다른 사본을 무효화해 혼자 수정할 권한을 얻는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: 더티 데이터를 보유하면서 다른 캐시에 공유 읽기를 허용하는 MOESI 전용 상태.
- **더티 공유(Dirty Sharing)**: 메모리에 아직 기록되지 않은 최신 더티 데이터를 여러 캐시가 공유하는 방식.

</details>

| 일관성 프로토콜 | MESI | MOESI |
|:---|:---|:---|
| 적용 기준 | 4상태 기반의 단순한 소유권 관리 | **더티 공유**로 메모리 쓰기 트래픽 완화 필요 |
| 핵심 특징 | M·E·**S**·I 상태의 **단일 작성자** 소유권 관리 | **O 상태** 추가로 더티 데이터 공유 허용 |
| 한계 | 더티 데이터 공유 요구 시 메모리 경유 비용 | 상태·메시지·검증 복잡도 증가 |

#### 한줄 요약
- MESI는 클린 공유와 단독 수정을 명확히 나누고, MOESI는 더티 데이터도 다른 코어가 읽게 해 메모리 왕복 전송을 줄인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 간 전달(Cache-to-Cache Transfer, C2C)**: 메모리 대신 최신 라인을 보유한 다른 캐시가 데이터를 직접 전달하는 방식.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립적으로 갱신하는 변수를 서로 다른 캐시 라인에 배치해 거짓 공유를 방지하는 기법.
- **정형 검증(Formal Verification)**: 상태 전이 규칙이 모든 가능한 경우에서 불변식을 지키는지 수학적으로 확인하는 검증 방법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 여러 코어의 반복 소유권 교환으로 **거짓 공유** | 데이터 소유 코어 중심 배치·**캐시 라인 패딩** | 무효화 핑퐁·인터커넥트 트래픽 감소 |
| 최신 데이터 요청이 메모리까지 전달 지연 | **C2C**·데이터 지역성 최적화 | 최신 사본 전달 지연 완화 |
| 동시 요청에서 상태 전이 오류 | **정형 검증**·상태 머신 자동 시험 | **단일 작성자 불변식** 위반 방지 |
| 코어 수 증가로 일관성 인터커넥트 트래픽 급증 | 디렉터리 기반 프로토콜 전환 검토 | 브로드캐스트 범위 제한·확장성 향상 |

#### 한줄 요약
- 캐시 일관성 비용은 프로토콜만으로 줄지 않으며, 데이터 소유 코어 배치와 변수 배치까지 맞춰야 소유권 충돌이 줄어든다.

## Ⅶ. 결론

- 단순한 상태 검증은 **MESI**, 더티 데이터의 캐시 간 공유가 잦으면 **MOESI**를 선택하고, 코어 수가 커지면 상태 수보다 디렉터리 기반 메시지 범위 축소를 우선

#### 한줄 요약
- 일관성 프로토콜은 이름이 아니라, 실제로 데이터를 얼마나 함께 읽고 얼마나 자주 서로 바꿔 쓰는지에 맞춰 고르는 구조다.
