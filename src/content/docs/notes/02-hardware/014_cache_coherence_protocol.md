## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **캐시 일관성 프로토콜**: 여러 코어의 캐시 사본 상태를 제어해 최신값과 단일 쓰기 권한을 보장하는 규약
- **소유권**: 캐시 라인을 수정하고 최신값을 제공할 수 있는 단일 권한과 책임
- **캐시 사본**: 같은 메모리 블록이 여러 코어의 사설 캐시에 복제되어 저장된 데이터

</details>

- 정의/개념: **소유권 상태** 기반 캐시 사본 일관성 규약
- 배경/필요성: 상태 규약 없이는 복제 캐시가 **서로 다른 최신값** 보유

#### 한줄 요약

- 복제 캐시의 최신값과 **단일 쓰기 권한** 보장

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **단일 작성자 불변식**: 쓰기 가능한 캐시 사본은 하나만 존재해야 한다는 규칙
- **다중 독자 불변식**: 쓰기 사본이 없을 때만 읽기 사본을 여러 개 허용하는 규칙
- **쓰기 직렬화**: 같은 주소의 여러 쓰기를 모든 코어가 동일한 순서로 관측하게 하는 성질
- **거짓 공유**: 독립 변수가 같은 캐시 라인에 있어 서로의 쓰기가 불필요한 무효화를 일으키는 현상
- **캐시 라인**: 캐시 간 전송과 무효화가 적용되는 고정 크기 데이터 블록

</details>

- **단일 작성자•다중 독자** 불변식으로 쓰기 사본 단일화
- **쓰기 직렬화** 로 모든 코어의 관측 순서 통일
- 무효화 단위가 변수가 아닌 **캐시 라인** 전체

#### 한줄 요약

- **단일 작성자•다중 독자** 보장과 거짓 공유 발생

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **상태 비트**: 캐시 라인의 읽기•쓰기 권한과 변경 여부를 부호화한 비트
- **일관성 제어기**: 로컬•원격 요청에 따라 라인 상태와 소유권 전이를 결정하는 회로
- **일관성 연결망**: 캐시 사이의 소유권•무효화 요청과 최신 데이터를 전달하는 통신 경로
- **공유 메모리 계층**: 여러 코어가 함께 접근하는 최종 캐시나 주기억장치로 원본 데이터와 축출값을 수용한다.
- **더티 축출**: 메모리보다 최신인 캐시 라인을 교체하기 전에 하위 계층에 기록하는 동작

</details>

```text
[캐시 라인•상태비트] -- [일관성 제어기] -- [일관성 연결망] -- [공유 메모리 계층]
```

선의 의미: 캐시 라인 권한을 판정하는 제어기와 소유권•무효화•최신값을 전달하는 연결망 및 공유 메모리 사이의 정적 인터페이스 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인•상태비트 | **읽기•쓰기 권한** 보관 |
| 일관성 제어기 | 상태 전이와 **소유권 판정** |
| 일관성 연결망 | 요청•무효화•**데이터 전달** |
| 공유 메모리 계층 | 원본 보관과 **더티 축출** 수용 |

#### 한줄 요약
- 상태 비트와 제어기가 권한을 판단하고 연결망과 메모리 계층이 무효화와 최신값 전달을 수행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **무효화**: 쓰기 전에 다른 캐시가 가진 사본의 사용 권한을 회수하는 동작
- **쓰기 소유권 요청**: 공유 또는 무효 상태의 코어가 독점 수정 권한을 얻기 위해 보내는 요청
- **최신값 전달**: 메모리보다 최신인 더티 사본을 요청 코어에 제공하는 동작
- **M 상태**: Modified, 메모리보다 최신이며 단독 쓰기가 가능한 상태
- **E 상태**: Exclusive, 메모리와 같고 단독 읽기•쓰기가 가능한 상태
- **S 상태**: Shared, 여러 캐시가 읽기 사본을 보유한 상태
- **I 상태**: Invalid, 캐시 라인을 사용할 수 없는 상태
- **일관성 트랜잭션**: 소유권 요청•무효화•데이터 전달을 연결망에서 하나의 권한 전환 절차로 수행하는 동작
- **로컬 일관성 제어기**: 요청 코어의 캐시 상태를 판정하고 상태 전이를 실행하는 회로
- **원격 일관성 제어기**: 다른 코어의 캐시 상태를 판정하고 무효화를 실행하는 회로

</details>

```text
                    [캐시 라인 접근]
                            |
                   1. 로컬 상태 판정
                     /              \
                  [읽기]            [쓰기]
                    |                 |
             [I 상태인가?]      [M•E 상태인가?]
               /       \          /          \
             [예]      [아니요]  [예]         [아니요]
              |          |        |             |
       2. 읽기 사본 확보 [현재값 반환] |      3. 쓰기 소유권 요청
              |                   |             |
       [다른 사본 존재?]          |      4. 원격 사본 무효화
          /         \             |             |
        [예]        [아니요]       |             |
         |             |           |             |
       [S 전이]      [E 전이]       +------+------+
                                            |
                                    5. M 전이•쓰기 허용
                                            |
                                       [최신값 유지]
```

**동작 원리**

- **1. 로컬 상태 판정**: M•E•S•I 권한 확인
- **2. 읽기 사본 확보**: 공유 여부에 따라 E 또는 S 전이
- **3. 쓰기 소유권 요청**: S•I에서 독점 권한 요청
- **4. 원격 사본 무효화**: 다른 캐시의 읽기•쓰기 권한 회수
- **5. M 전이•쓰기 허용**: 단일 작성자 권한 확정

#### 한줄 요약

- 로컬 상태 판정 후 필요한 **권한 전이•무효화** 수행

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **MESI**: Modified, Exclusive, Shared, Invalid 상태로 라인을 관리하는 프로토콜
- **MOESI**: Modified, Owned, Exclusive, Shared, Invalid 상태로 라인을 관리하는 프로토콜
- **소유 상태**: 최신 더티 데이터를 제공하면서 메모리 반영 책임을 유지하는 MOESI 상태
- **더티 공유**: 수정된 캐시 라인을 메모리에 먼저 쓰지 않고 다른 캐시에 최신값으로 전달하는 동작
- **반영 책임**: 소유 캐시가 더티 데이터를 최종적으로 메모리에 기록해야 하는 의무

</details>

| 일관성 프로토콜 | MESI | MOESI |
|:---|:---|:---|
| 적용 기준 | **더티 공유** 가 드문 경우 | 수정값의 즉시 공유가 잦은 경우 |
| 핵심 특징 | 공유 전 **메모리 반영** | **소유 상태** 의 직접 전달 |
| 한계 | 공유 시 **메모리 트래픽** | 소유 사본의 **반영 책임** |

> 요약: MOESI는 소유 상태로 메모리 왕복 절감

#### 한줄 요약

- MESI의 메모리 반영과 MOESI의 **소유 상태** 절충

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **캐시 라인 패딩**: 독립 변수를 서로 다른 라인에 배치하도록 빈 공간을 추가하는 기법
- **소유권 지역화**: 특정 데이터를 주로 한 코어가 수정하게 배치해 권한 이동을 줄이는 방법
- **전이 스트레스 검증**: 드문 상태 전이와 요청 경합을 반복 생성해 프로토콜 불변식을 확인하는 시험
- **데이터 분할**: 공유 데이터를 독립 영역으로 나누어 소유권 이동을 줄이는 방법
- **코어별 배치**: 데이터를 주로 접근하는 코어 가까이에 배치하는 방법
- **캐시 간 전달**: 최신 데이터를 메모리를 거치지 않고 소유 캐시에서 요청 캐시로 직접 보내는 동작
- **프로토콜 불변식**: 어떤 상태 전이에서도 단일 쓰기 권한과 최신값 제공이 깨지지 않아야 한다는 규칙

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 라인의 **무효화 왕복** | **소유권 지역화•데이터 분할** | **일관성 트래픽** 감소 |
| 독립 변수의 **거짓 공유** | **캐시 라인 패딩•코어별 배치** | 불필요한 **사본 회수** 방지 |
| 더티 공유의 **메모리 왕복** | **MOESI•캐시 간 전달** | **최신값 지연** 감소 |
| 드문 전이의 **데이터 불일치** | **불변식•전이 스트레스** 검증 | **프로토콜 정확성** 확보 |

#### 한줄 요약

- 더티 공유가 잦으면 MOESI의 소유 상태로 최신값을 전달하고 메모리 반영을 미뤄 트래픽을 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **메모리 왕복**: 최신 데이터를 공유하기 위해 캐시에서 메모리로 쓴 뒤 다시 읽는 통신 비용

</details>

- 더티 공유가 드물면 **MESI**, 잦으면 **MOESI** 선택

#### 한줄 요약

- 더티 공유는 **MESI•MOESI**, 거짓 공유는 배치 분리 결정
