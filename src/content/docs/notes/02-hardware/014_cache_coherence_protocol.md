## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성(Cache Coherence)**: 다중 코어가 동일한 물리 메모리 주소를 각자의 사설 캐시에 복사해 사용할 때, 한 코어의 데이터 수정이 다른 모든 코어에 즉각 반영되어 단일 메모리 뷰를 제공하는 하드웨어 메커니즘.
- **SWMR 불변식(Single-Writer, Multiple-Reader Invariant)**: 특정 메모리 위치에 대해 주어진 시점에 단 1개의 코어만 쓰기(Write) 권한을 갖거나, 다수의 코어가 읽기(Read) 권한만을 가질 수 있다는 일관성의 핵심 불변 법칙.
- **무효화 기반(Invalidation-based)**: 한 코어가 캐시 라인을 수정할 때 다른 모든 코어의 사본을 무효화(Invalid) 상태로 변경하는 프로토콜.

</details>

- 정의/개념: 다중 코어 프로세서 환경에서 동일한 메모리 주소에 대한 사설 캐시 사본 간의 데이터 불일치를 방지하고 단일 메모리 뷰를 제공하는 하드웨어 **상태 전이 프로토콜**
- 배경/필요성: 멀티코어 시스템에서 코어별 사설 캐시에 분산 적재된 동일 메모리 블록 사본 간의 독립적 수정으로 인한 **데이터 불일치** 발생을 원천 차단하기 위한 공유 규칙 필수화

#### 한줄 요약
- 캐시 일관성 프로토콜은 멀티코어 환경에서 SWMR 불변식을 유지하여 사설 캐시 간의 데이터 일치성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **버스 트랜잭션(Bus Transaction)**: 일관성을 유지하기 위해 온칩 인터커넥트나 시스템 버스를 통해 코어 간에 주고받는 하드웨어 메시지(BusRd, BusRdX, BusUpgr 등).
- **스누핑(Snooping)**: 모든 캐시 제어기가 시스템 버스에 브로드캐스트되는 트랜잭션 주소를 상시 감시하는 기법.
- **메모리 배리어(Memory Barrier)**: 컴파일러 및 비순차 실행 하드웨어에 의한 메모리 명령어 재배치를 억제하고 순서를 강제하는 동기화 명령어.

</details>

- SWMR 불변식 준수: 단일 시점에 복수 코어 읽기(**공유**) 또는 단일 코어 쓰기(**독점**)만을 허용하여 일관성 유지
- 하드웨어 상태 전이: 캐시 라인마다 상태 비트를 부여하고 버스 트랜잭션 수신 시 **하드웨어 유한상태머신**으로 자동 전이
- 일관성과 동기화의 분리: 캐시 일관성은 단일 주소 정합성을 보장하고, 주소 간 순서화는 **메모리 배리어**, 임계 구역은 락으로 통제

#### 한줄 요약
- 일관성은 단일 주소의 최신성 보장 규칙이고, 상태 머신 전이를 통해 구현되며, 메모리 배리어 및 락과 결합되어 전체 동기화를 완성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스누프 필터(Snoop Filter)**: 어떤 코어가 어떤 캐시 라인을 보유하고 있는지 추적하여, 해당 라인을 갖지 않은 코어로의 불필요한 스누프 브로드캐스트를 차단하는 하드웨어 필터.
- **온칩 인터커넥트(On-Chip Interconnect)**: 멀티코어 다이 내부에서 코어, 사설 캐시, LLC, 메모리 제어기를 연결하는 고속 통신망(링 버스, 2D 메시 등).

</details>

```text
+-----------------------------------------------------------------------+
| 멀티코어 캐시 일관성 하드웨어 서브시스템                              |
|  +---------------------------+     +-------------------------------+  |
|  | 코어 0 사설 캐시          |     | 코어 1 사설 캐시              |  |
|  |  - [M|E|S|I 상태 비트]    |     |  - [M|E|S|I 상태 비트]        |  |
|  |  - 캐시 라인 데이터 (64B) |     |  - 캐시 라인 데이터 (64B)     |  |
|  |  - 스누퍼 및 FSM 제어기   |     |  - 스누퍼 및 FSM 제어기       |  |
|  +-------------+-------------+     +---------------+---------------+  |
|                |                                   |                  |
|  +-------------v-----------------------------------v---------------+  |
|  | 온칩 일관성 인터커넥트 버스 (Snooping Bus / Crossbar / 2D Mesh) |  |
|  |  - 일관성 트랜잭션 브로드캐스트: BusRd, BusRdX, BusUpgr        |  |
|  +-----------------------------+-----------------------------------+  |
|                                |                                      |
|  +-----------------------------v-------------------------------+      |
|  | 스누프 필터(Snoop Filter) 및 디렉터리 제어기                |      |
|  |  - 사본 보유 코어 추적 및 불필요한 브로드캐스트 차단         |      |
|  +-----------------------------+-------------------------------+      |
|                                |                                      |
|  +-----------------------------v-------------------------------+      |
|  | 공유 L3 캐시(LLC) 및 외부 주메모리(DRAM) 인터페이스         |      |
+--+-------------------------------------------------------------+------+
```

선의 의미: `+---+`는 프로세서 및 캐시 서브시스템 경계, `->`는 일관성 패킷 및 데이터 트랜잭션 전송 흐름

| 구성요소 | 책임 |
|:---|:---|
| 상태 비트 | 각 캐시 라인의 **MESI 상태 플래그**를 유지하여 접근 권한 정의 |
| 캐시 제어기 FSM | 로컬 명령어 및 원격 스누프 수신에 따른 **상태 전이** 자동 수행 |
| 일관성 인터커넥트 | BusRd, BusRdX, BusUpgr 등 일관성 패킷을 타 코어로 고속 브로드캐스트 |
| 스누프 필터·디렉터리 | 사본 보유 코어를 추적하여 불필요한 버스 **스누핑 트래픽 억제** |

#### 한줄 요약
- 캐시 일관성 시스템은 라인별 상태 비트, 캐시 제어기, 온칩 인터커넥트, 스누프 필터가 유기적으로 맞물려 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 라인이 단독 수정되어 메모리와 불일치(Dirty)하며, 축출 시 메모리 되쓰기 책임이 있는 상태.
- **독점(Exclusive, E)**: 단일 캐시만 사본을 보유하고 메모리와 일치(Clean)하여, 버스 트랜잭션 없이 즉시 쓸 수 있는 상태.
- **공유(Shared, S)**: 복수의 캐시가 동일한 클린 사본을 공유하며, 읽기만 가능하고 쓰기 시 무효화가 선행되어야 하는 상태.
- **무효(Invalid, I)**: 유효한 데이터가 없거나 타 코어의 쓰기로 사본이 무효화된 상태.
- **BusRdX / BusUpgr**: 쓰기 권한 획득을 위해 타 캐시 사본을 모두 무효화(Invalidate)시키는 버스 트랜잭션.

</details>

```text
[로컬 코어 메모리 접근 요청]
             │
             ├──────────────────────────┐
             ▼                          ▼
    1. 로컬 읽기 (Read Miss)   2. 로컬 쓰기 (Write Request)
             │                          │
             ▼                          ├─ I 상태: BusRdX 발행 ➔ M 전이
     BusRd 트랜잭션 발행                ├─ S 상태: BusUpgr 발행 ➔ M 전이
             │                          ├─ E 상태: 버스 없이 M 즉시 승격
             ▼                          └─ M 상태: 캐시 즉시 쓰기 완료
     타 캐시 사본 유무 판별             │
      ├─ 존재: S 상태 전이              ▼
      └─ 무존재: E 상태 전이    [타 코어로 무효화 신호 전파]
                                        │
                                        ▼
                                3. 원격 스누프 감지
                                 ├─ BusRd 수신: M 보유 시 제공 후 S 전이
                                 └─ BusRdX 수신: 보유 라인 즉시 I 전이
```

분기 결과: E 상태 쓰기는 **버스 트랜잭션 없이 즉시 완료**, S/I 상태 쓰기는 **무효화 트랜잭션 선행**

**동작 원리**

1. **로컬 읽기 요청(Read Miss)**: 로컬 캐시에 데이터가 없을 때 BusRd 트랜잭션을 발행하며, 타 캐시 보유 여부에 따라 S(Shared) 또는 E(Exclusive) 상태로 전이함
2. **로컬 쓰기 요청(Write Hit/Miss)**: S 또는 I 상태에서 쓰기 시 BusUpgr 또는 BusRdX를 발행하여 타 캐시 사본을 무효화(I)한 후 M(Modified) 상태로 승격하여 쓰기를 완료함
3. **원격 스누프 감지(BusRd 수신)**: M 상태 보유 중 타 코어의 BusRd 수신 시 최신 데이터를 제공하고 자신은 S 상태로 변경함
4. **원격 무효화 감지(BusRdX 수신)**: 타 코어의 BusRdX 또는 BusUpgr 수신 시 자신이 보유한 M/E/S 라인을 즉시 I(Invalid) 상태로 강제 무효화함

#### 한줄 요약
- MESI 프로토콜은 로컬 요청과 원격 스누프 신호에 따라 M, E, S, I 4개 상태를 상호 전이시키며 SWMR 불변식을 유지한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: MOESI에서 메모리에 되쓰지 않은 더티 사본을 보유한 채 타 캐시와 공유를 허용하며, 데이터 응답 책임을 독점하는 상태.
- **전달(Forward, F)**: MESIF에서 다수의 클린 공유 사본 중 단 1개 라인만 데이터 응답 책임을 전담하는 상태.

</details>

| 캐시 일관성 프로토콜 | MESI 프로토콜 | MESIF 프로토콜 (Intel) | MOESI 프로토콜 (AMD) |
|:---|:---|:---|:---|
| 적용 기준 | **소규모 멀티코어** 및 표준 일관성 요구 | **대규모 공유 읽기** 및 버스 응답 병목 해소 | **더티 데이터 빈번 공유** 및 DRAM 쓰기 절감 |
| 상태 구성 | M, E, S, I (4가지 기본 상태) | M, E, S, I + F (Forward) | M, E, S, I + O (Owned) |
| 핵심 메커니즘 | 표준 **무효화 기반** 일관성 프로토콜 | 클린 공유 사본 중 1개만 **응답자 지정** | 더티 데이터를 메모리에 안 쓰고 **코어 간 직접 공유** |
| 장점 | 구조 단순 및 하드웨어 회로 비용 최소 | 다중 공유 시 중복 버스 응답 대역폭 낭비 제거 | 더티 라인 공유 시 DRAM 되쓰기 트래픽 대폭 절감 |
| 한계 | 더티 데이터 공유 시 메모리 되쓰기 지연 수반 | F 상태 이전 및 유지 관리 회로 추가 | O 상태 보유 코어의 응답 부담 집중 |

#### 한줄 요약
- 기본은 MESI이며, 클린 공유 트래픽 절감에는 MESIF(Forward), 더티 데이터 공유 지연 절감에는 MOESI(Owned)가 최적화된 확장이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거짓 공유(False Sharing)**: 서로 다른 코어가 독립된 변수를 갱신하지만 동일한 64B 캐시 라인에 위치하여 불필요한 무효화가 반복되는 현상.
- **캐시 라인 핑퐁(Cache Line Ping-Ponging)**: 여러 코어가 동일 캐시 라인을 번갈아 수정하여 소유권이 코어 간을 지속 왕복하는 병목 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수가 한 라인에 묶여 거짓 공유 및 핑퐁 발생 | **캐시 라인 패딩** 및 스레드 로컬 저장소 활용 | 불필요한 일관성 무효화 트래픽 및 버스 정체 제거 |
| 코어 수 증가에 따른 스누프 브로드캐스트 트래픽 포화 | **스누프 필터** 및 디렉터리 기반 구조 전환 | 사본 보유 노드에만 선택적 통지하여 확장성 보장 |
| 더티 데이터 공유 시 DRAM 왕복 지연 발생 | **MOESI 프로토콜** 및 캐시 간 직접 전송 채택 | 메인 메모리 접근 생략으로 데이터 공급 지연 단축 |

#### 한줄 요약
- 캐시 일관성 실무 최적화는 거짓 공유 방지를 위한 64B 패딩, 스누프 필터 기반 브로드캐스트 억제, MOESI 캐시 간 직접 전송으로 완성된다.

## Ⅶ. 결론

- 대칭형 멀티코어(SMP)의 데이터 무결성을 보장하는 핵심 기저 기술로 정착되었으며, 최근 수십에서 수백 코어로 확장되는 매니코어 및 멀티 칩렛 환경에서는 브로드캐스트 대역폭 한계를 극복하기 위해 **디렉터리 기반 일관성 프로토콜과 CXL.mem 하드웨어 일관성 인터커넥트**로 고도화 진화 중이므로, 시스템 설계 시 스레드 간 공유 빈도와 통신 토폴로지를 분석하여 적정 일관성 프로토콜 및 인터커넥트 방식을 결정해야 함

#### 한줄 요약
- 캐시 일관성은 단일 주소 정합성을 보장하는 하드웨어 기초이며, 메모리 배리어와 락이 결합되어 완전한 동시성 시스템을 완성한다.
