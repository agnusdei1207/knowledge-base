## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 멀티코어 환경에서 복수 캐시 사본들 간의 쓰기 독점권과 최신 읽기 일관성을 유지하는 상태 전이 규약이다.
- **소유권(Ownership)**: 캐시 라인 데이터를 직접 수정할 수 있고 하위 메모리나 타 캐시로 최신 데이터를 제공할 책임을 갖는 독점 권한이다.
- **캐시 사본(Cache Copy)**: 메인 메모리의 데이터가 여러 독립 코어의 사설 캐시에 적재되어 복제된 물리적 사본이다.

</details>

- 정의: 사설 캐시에 복제된 데이터 사본의 **소유권**과 최신 상태를 제어하는 하드웨어 **캐시 일관성 프로토콜**
- 배경: 다중 코어 환경에서 구버전 데이터를 읽어 발생하는 비일관성 오류와 시스템 데이터 파괴를 방지하기 위함

#### 한줄 요약

- 복수 멀티코어 캐시 간의 쓰기 독점 권한과 데이터 일관성을 상태 전이로 보장하는 하드웨어 제어 규약이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **단일 작성자 불변식(Single Writer Invariant)**: 특정 시점에 동일 주소 캐시 라인을 수정할 수 있는 쓰기 독점 권한은 오직 1개의 캐시만 보유한다는 규칙이다.
- **다중 독자 불변식(Multiple Reader Invariant)**: 쓰기 권한 소유자가 없을 때 무수한 코어가 동시에 읽기 사본을 공유할 수 있다는 규칙이다.
- **쓰기 직렬화(Write Serialization)**: 동일 주소에 대한 복수 쓰기 요청이 인터커넥트 중재를 통해 전역적으로 동일한 순서로 실행되도록 순서화하는 성질이다.
- **거짓 공유(False Sharing)**: 서로 다른 변수가 동일 라인에 위치하여 한 코어의 쓰기가 타 코어의 사본까지 무효화시키는 현상이다.

</details>

- **단일 작성자 불변식**과 **다중 독자 불변식**을 준수하여 쓰기 독점권 보유 시 타 사본을 모두 파기함.
- **쓰기 직렬화**를 보장하여 모든 코어가 동일 주소의 데이터 변경을 동일한 순서로 관측함.
- 무효화 제어 단위가 64바이트 단위로 구동되어 **거짓 공유** 병목을 수반할 수 있음.

#### 한줄 요약

- 단일 작성자 및 다중 독자 불변식을 만족시키고 쓰기 직렬화를 통해 전역적인 메모리 일관성을 유지한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 캐시 라인에 배치되어 해당 라인의 현재 일관성 상태를 기록하는 하드웨어 플래그이다.
- **일관성 연결망(Coherence Interconnect)**: 일관성 통신 패킷이나 중재 메시지를 주고받는 온칩 인터커넥트 회로망이다.
- **공유 메모리 계층(Shared Memory Hierarchy)**: 모든 코어가 공유하며 축출되는 더티 데이터를 수용하는 최상위 메모리 계층이다.

</details>

```text
[ 캐시 일관성 제어기 구조 ]
+-----------------------------------------------------------+
| 캐시 라인 항목 : [유효 비트] [더티 비트] [상태 비트]      |
| 상태 비트 구성 : 수정(M) / 소유(O) / 독점(E) / 공유(S)    |
+-----------------------------------------------------------+
| 일관성 제어기 (상태 전이 엔진)                            |
|  - 로컬 코어 요청 : 읽기, 쓰기                            |
|  - 원격 버스 요청 : 읽기, 무효화, 업그레이드              |
+-----------------------------------------------------------+
| 일관성 연결망 (버스 및 라우터)                            |
+-----------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| 상태 비트 | 라인의 권한 및 변경 상태 표시 |
| 일관성 제어기 | 로컬 및 원격 요청에 따른 상태 전이 수행 |
| 일관성 연결망 | 통신 메시지 전달 및 제어권 중재 |
| 공유 메모리 계층 | 축출 더티 라인 수용 및 최종 상태 보존 |

#### 한줄 요약

- 상태 비트와 일관성 제어기, 인터커넥트가 결합하여 코어 간 소유권 패킷을 중계하고 상태를 갱신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정 상태(Modified)**: 데이터가 메모리와 다르게 최신 갱신되었으며 오직 해당 캐시만 독점 소유권을 가진 상태이다.
- **독점 상태(Exclusive)**: 데이터가 메모리와 일치하며 타 캐시 사본 없이 오직 단독으로 보유한 상태이다.
- **공유 상태(Shared)**: 데이터가 메모리와 일치하며 타 캐시에도 동일 사본이 병렬로 존재하는 읽기 전용 상태이다.
- **무효 상태(Invalid)**: 데이터가 유효하지 않거나 타 코어의 쓰기로 인해 파기되어 접근할 수 없는 상태이다.
- **무효화(Invalidation)**: 타 코어가 쓰기 권한을 요청했을 때 자신의 사본 상태를 무효로 파기하는 제어 동작이다.

</details>

```text
[ 지역 쓰기 요청 발생 ]
          │
          ▼
    [ 로컬 상태 확인 ]
          │
    ├─ 수정 상태 ──> 즉시 쓰기 완료
    ├─ 독점 상태 ──> 수정 상태 전이 후 쓰기
    └─ 공유 또는 무효 상태
          │
          ▼
[ 일관성 연결망으로 소유권 및 무효화 요청 전송 ]
          │
          ▼
[ 원격 코어의 기존 사본을 무효 상태로 강제 변경 ]
          │
          ▼
[ 로컬 캐시를 수정 상태로 승격 후 쓰기 완결 ]
```

### 동작 원리

1. 상태 확인: 로컬 갱신 전 현재 상태를 확인함.
2. 소유권 획득: 공유 상태나 무효 상태일 때 연결망을 통해 소유권을 요청함.
3. 사본 무효화: 원격 캐시의 사본을 **무효 상태**로 강제 변경하여 무효화함.
4. 상태 승격: 로컬 사본을 **수정 상태**로 승격한 후 로컬 쓰기를 완결함.

#### 한줄 요약

- 로컬 상태 확인 후 공유나 무효 상태일 때 원격 사본을 모두 파기하고 수정 상태로 승격하여 쓰기를 완료한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MESI**: 수정, 독점, 공유, 무효의 4가지 상태를 사용하여 대중적으로 채택된 일관성 프로토콜이다.
- **MOESI**: 소유 상태를 추가하여 메모리 쓰기 없이도 변경된 데이터를 직접 공유할 수 있는 최적화 프로토콜이다.
- **소유 상태(Owned)**: 데이터가 메모리와 불일치하지만 다른 코어에 공유 사본을 제공하면서 최종 쓰기 책임을 독점 보존하는 상태이다.
- **더티 공유(Dirty Sharing)**: 메인 메모리로 플러시하지 않고도 캐시 통신을 통해 더티 데이터를 공유하는 기술이다.

</details>

| 비교 항목 | MESI 프로토콜 | MOESI 프로토콜 |
|:---|:---|:---|
| 상태 구성 | 수정, 독점, 공유, 무효 | 수정, **소유 상태**, 독점, 공유, 무효 |
| 더티 공유 여부 | 개별 하드웨어 구현에 의존함 | **소유 상태**를 기반으로 **더티 공유** 제공 |
| 메모리 트래픽 | 쓰기 책임 이전에 구조적 제약 존재 | 지연 쓰기를 통한 트래픽 대폭 절감 |
| 데이터 제공자 | 수정 상태 캐시 또는 메모리 계층 | **소유 상태** 캐시가 메모리 대신 직접 제공 |
| 하드웨어 복잡도 | 4상태 기반의 제어 구조 적용 | 5상태 전이 제어로 구현 로직 복잡 |

#### 한줄 요약

- MESI는 4개의 기본 상태로 제어하며 MOESI는 소유 상태를 통한 더티 공유로 메모리 접근 트래픽을 연기한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **소유권 지역화(Ownership Localization)**: 쓰기 작업을 가급적 동일 코어에 할당하여 무효화 핑퐁 현상을 예방하는 최적화 기법이다.
- **캐시 간 전달(Cache-to-Cache Transfer)**: 메모리까지 가지 않고 라우터를 통해 상태 캐시에서 직접 데이터를 쏘아주는 고속 전송이다.
- **프로토콜 불변식(Protocol Invariant)**: 비순차 수신이나 동시 승격 시 단일 작성자 불변식이 깨지지 않도록 보장하는 논리 검증 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복수 코어의 교차 쓰기로 소유권 핑퐁 및 트래픽 폭증 | 스레드 스케줄링 **소유권 지역화** 설정 적용 | 불필요한 무효화 통신 트래픽의 파괴적 절감 |
| 데이터 공유 요청 시 매번 메모리 기록으로 인한 지연 발생 | MOESI 프로토콜 채택 및 **캐시 간 전달** 인프라 연동 | 메모리 쓰기 억제 및 데이터 공유 지연시간 극소화 |
| 독립 변수가 동일 라인에 겹쳐 발생하는 잦은 거짓 공유 | 자료구조 선언 시 캐시 라인 패딩 최적화 연동 | 구조체 패딩을 통한 불필요한 라인 무효화 방어 |
| 동시 접근 시 상태 전이 오류로 인한 **프로토콜 불변식** 위반 | 정형 검증을 통한 상태 머신 코너케이스 스트레스 테스트 | 멀티코어 메모리 오염 및 데이터 경합 원천 차단 |

#### 한줄 요약

- 소유권 지역화 스케줄링과 캐시 간 전달 확충, 철저한 불변식 검증을 통해 일관성 병목과 핑퐁 오류를 방지한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **프로토콜 선택 기준(Protocol Selection Criteria)**: 공유 쓰기 패턴, 온칩 라우터 대역폭, 메모리 접근 지연을 종합 평가하여 최적 구조를 결정하는 가이드라인이다.

</details>

- 더티 공유가 빈번하면 **MOESI**, 제어 단순성이 우선이면 **MESI**를 선택함

#### 한줄 요약

- 공유 패턴과 온칩 네트워크 대역폭 비용을 기준으로 상태 확장 여부와 캐시 전송 최적화를 결정해야 한다.
