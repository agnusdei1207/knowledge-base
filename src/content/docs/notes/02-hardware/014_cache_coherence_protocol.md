## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 여러 사설 캐시에 복제된 데이터의 쓰기 권한과 최신 읽기 값을 상태 전이로 관리하는 규약입니다.
- **소유권(Ownership)**: 특정 캐시 라인을 수정하거나 최신 데이터를 제공할 수 있는 권한과 책임입니다.
- **단일 작성자 불변식(Single-Writer Invariant)**: 같은 메모리 위치를 수정할 수 있는 권한은 한 시점에 하나의 코어만 가진다는 원칙입니다.

</details>

- 정의/개념: 복제 캐시의 쓰기 권한과 최신 값을 관리하는 **상태 전이 규약**
- 배경/필요성: 오래된 사본 읽기와 동시 쓰기 충돌 방지

#### 한줄 요약

- 여러 사람이 같은 문서를 복사해 보관할 때, 한 사람만 수정권을 갖고 나머지는 최신본을 읽도록 정하는 약속이 캐시 일관성 프로토콜입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다중 독자(Multiple Readers)**: 수정 권한이 없는 여러 캐시가 같은 최신 클린 데이터를 함께 읽는 상태입니다.
- **쓰기 직렬화(Write Serialization)**: 같은 주소의 여러 쓰기 요청을 모든 코어가 같은 순서로 관찰하게 하는 성질입니다.
- **거짓 공유(False Sharing)**: 서로 다른 데이터가 한 캐시 라인에 있어 독립 갱신에도 무효화가 발생하는 현상입니다.

</details>

- 한 라인에 하나의 쓰기 권한을 보장하는 **단일 작성자**
- 공유 읽기 순서를 맞추는 **쓰기 직렬화**
- 라인 단위 공유에서 생기는 **거짓 공유 비용**

#### 한줄 요약

- 일관성은 여러 코어가 같은 값을 읽게 하는 것뿐 아니라, 누가 먼저 썼는지를 모두가 같은 순서로 보게 해 프로그램이 예측 가능하게 만드는 규칙입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 캐시 라인의 수정, 공유, 무효 상태를 나타내는 제어 비트입니다.
- **일관성 제어기(Coherence Controller)**: 로컬 요청과 원격 메시지에 따라 캐시 라인 상태를 전이시키는 회로입니다.
- **일관성 인터커넥트(Coherence Interconnect)**: 일관성 요청, 응답, 데이터 전달을 코어 사이에 운반하는 연결망입니다.

</details>

```text
[캐시 일관성 구성]
├─ 캐시 라인
│  ├─ 데이터
│  └─ 상태 비트
├─ 일관성 제어기
├─ 일관성 인터커넥트
└─ 공유 메모리 계층
```

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 데이터와 소유·공유 상태 보관 |
| 상태 비트 | 수정·공유·무효 권한 표시 |
| 일관성 제어기 | 로컬·원격 요청별 상태 전이 |
| 일관성 인터커넥트 | 무효화·소유권·데이터 메시지 전달 |
| 공유 메모리 계층 | 최종 데이터 보관과 미스 응답 |

#### 한줄 요약

- 각 캐시는 데이터 옆에 현재 권한을 적어 두고, 제어기와 인터커넥트가 그 권한을 다른 코어와 조정합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 한 캐시만 최신 더티 데이터를 가지고 수정할 수 있는 MESI 상태입니다.
- **독점(Exclusive, E)**: 한 캐시만 클린 데이터를 가지고 있으며 로컬 쓰기로 M이 될 수 있는 MESI 상태입니다.
- **공유(Shared, S)**: 여러 캐시가 같은 클린 데이터를 읽을 수 있는 MESI 상태입니다.
- **무효(Invalid, I)**: 해당 캐시 라인의 데이터가 없거나 사용할 수 없는 MESI 상태입니다.

</details>

```text
[1. 로컬 쓰기 요청]
          │
          ▼
[2. M·E·S·I 상태 확인]
          │
          ├─ M·E
          │     │
          │     ▼
          │  [3. M 상태의 로컬 갱신]
          │
          └─ S·I
                │
                ▼
           [3. 소유권 요청·원격 사본 무효화]
                │
                ▼
           [4. M 상태의 로컬 갱신]
```

동작 원리:

1. 로컬 쓰기 요청: 코어가 대상 캐시 라인 수정 요구
2. M·E·S·I 상태 확인: 현재 데이터와 쓰기 권한 보유 여부 판정
3. M 상태의 로컬 갱신 또는 소유권 요청·원격 사본 무효화: 권한 상태별 전이
4. M 상태의 로컬 갱신: 단일 작성자 권한 아래 데이터 수정

#### 한줄 요약

- 이미 혼자 가진 데이터면 바로 쓰고, 다른 코어와 공유한 데이터면 먼저 다른 사본을 무효화해 혼자 수정할 권한을 얻습니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: 더티 데이터를 보유하면서 다른 캐시에 공유 읽기를 허용하는 MOESI의 상태입니다.
- **더티 공유(Dirty Sharing)**: 메모리에 아직 기록되지 않은 최신 데이터를 여러 캐시가 공유하는 방식입니다.

</details>

| 일관성 프로토콜 | MESI | MOESI |
|:---|:---|
| 적용 기준 | 단순한 4상태 일관성 제어 | 더티 데이터 공유와 메모리 트래픽 완화 |
| 핵심 특징 | M·E·S·I 상태의 소유권 관리 | O 상태와 더티 공유 추가 |
| 한계 | 공유 더티 데이터 처리 유연성 제약 | 상태·메시지·검증 복잡도 증가 |

#### 한줄 요약

- MESI는 깨끗한 공유와 단독 수정을 명확히 나누고, MOESI는 아직 메모리에 쓰지 않은 최신 데이터도 다른 코어가 읽게 해 전송을 줄입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 간 전달(Cache-to-Cache Transfer, C2C)**: 메모리 대신 최신 라인을 가진 다른 캐시가 데이터를 직접 전달하는 방식입니다.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립 데이터를 서로 다른 캐시 라인에 배치해 거짓 공유를 줄이는 기법입니다.
- **정형 검증(Formal Verification)**: 상태 전이 규칙이 모든 가능한 경우에서 불변식을 지키는지 수학적으로 확인하는 검증입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 여러 코어가 같은 라인 소유권을 반복 교환 | 데이터 소유 코어 중심 배치 | 무효화 핑퐁과 인터커넥트 트래픽 감소 |
| 최신 데이터 요청이 메모리까지 전달 | C2C와 데이터 지역성 적용 | 최신 사본의 전달 지연 완화 |
| 독립 변수가 같은 라인으로 거짓 공유 | 캐시 라인 패딩과 자료구조 재배치 | 불필요한 무효화 감소 |
| 동시 요청에서 상태 전이 오류 발생 | 정형 검증과 상태 머신 시험 | 단일 작성자 불변식 위반 방지 |

#### 한줄 요약

- 캐시 일관성 비용은 프로토콜만으로 줄지 않으며, 데이터를 누가 주로 쓰는지와 변수 배치까지 맞춰야 소유권 싸움이 줄어듭니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **공유 패턴(Sharing Pattern)**: 여러 코어가 데이터 라인을 읽고 쓰는 빈도와 소유권 이동의 형태입니다.

</details>

- 코어 수와 **공유 패턴**이 단순하면 MESI를, 더티 공유의 메모리 트래픽 절감이 필요하면 MOESI를 선택하되 상태 전이 검증·거짓 공유·인터커넥트 비용으로 최종 결정

#### 한줄 요약

- 일관성 프로토콜은 이름이 아니라, 실제로 데이터를 얼마나 함께 읽고 얼마나 자주 서로 바꿔 쓰는지에 맞춰 고르는 구조입니다.
