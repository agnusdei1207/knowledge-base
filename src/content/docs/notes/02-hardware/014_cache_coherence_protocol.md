## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캐시 일관성 프로토콜(Cache Coherence Protocol)**: 다중 코어 프로세서의 개별 사설 캐시에 복제된 동일 주소의 데이터 사본들이 상호 불일치하지 않도록 상태 전이 및 버스 트랜잭션을 통해 정합성을 보장하는 하드웨어 통신 규약.
- **소유권(Ownership)**: 특정 캐시 블록을 독점적으로 수정할 수 있는 권한이자, 다른 코어의 읽기/쓰기 요청 시 메모리 대신 최신 데이터를 응답(Supply)해야 하는 하드웨어적 책임.
- **단일 작성자·다중 독자 불변식(Single-Writer-Multiple-Reader, SWMR)**: 임의의 주어진 시점에 특정 메모리 주소에 대해 단 하나의 코어만 쓰기 권한(Writer)을 갖거나, 다수의 코어가 읽기 전용 사본(Readers)만을 공유할 수 있도록 강제하는 일관성의 핵심 불변 규칙.
- **오래된 값(Stale Data)**: 타 코어에 의해 주기억장치나 캐시의 원본이 갱신되었으나 무효화 신호가 미처 도달하지 않아 사설 캐시에 잔존하는 비정합적 이전 데이터.

</details>

- 정의/개념: 멀티코어의 사설 캐시가 같은 주소를 복제할 때 **SWMR**을 상태 전이로 강제해 사본 정합성을 지키는 하드웨어 동기화 규약
- 배경/필요성: 코어별 사설 캐시가 같은 주소를 복제하는 구조에서 한 코어의 갱신이 타 사본에 전파되지 않아 **오래된 값** 읽기 발생

#### 한줄 요약
- 사설 캐시는 성능을 위해 사본을 늘리고 일관성 프로토콜은 그 사본을 다시 줄이므로, 두 힘의 균형점이 곧 멀티코어 성능의 상한이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 값 불변식(Data-Value Invariant)**: 쓰기 작업이 없는 구간에서 모든 캐시 사본의 데이터 값이 가장 최근에 수행된 쓰기 연산의 결과값과 반드시 일치해야 함을 규정하는 불변식.
- **메모리 일관성 모델(Memory Consistency Model)**: 서로 다른 메모리 주소에 대한 읽기/쓰기 연산들이 프로그램 실행 중 다중 코어에게 어떤 순서로 관찰되어야 하는지를 규정한 하드웨어-소프트웨어 간 상위 명세.
- **무효화 기반 프로토콜(Write-Invalidate)**: 특정 코어가 캐시 블록을 수정하기 전에 공유 버스를 통해 다른 모든 캐시의 사본을 무효 상태로 전환시켜 단독 소유권을 확보하는 프로토콜.
- **갱신 기반 프로토콜(Write-Update)**: 특정 코어가 캐시 블록을 수정할 때 변경된 데이터를 공유 버스를 통해 브로드캐스트하여 다른 모든 사설 캐시의 사본을 동시에 갱신하는 프로토콜.

</details>

- **SWMR**의 쓰기 권한 배타성과 **데이터 값 불변식**의 최신값 일치를 캐시 라인 상태 전이 하나로 동시에 강제하는 하드웨어 구현
- 일관성은 단일 주소의 사본 정합성만 책임지고, 서로 다른 주소 간 관찰 순서는 **메모리 일관성 모델**이 담당하는 별개 계층
- 상용 프로세서는 쓰기마다 대역폭을 쓰는 **갱신 기반 프로토콜** 대신 사본을 버리는 **무효화 기반 프로토콜**을 채택

#### 한줄 요약
- 일관성 프로토콜은 한 주소의 사본만 책임지므로, 락·배리어가 필요한 이유는 일관성이 부족해서가 아니라 애초에 다른 계층의 문제이기 때문이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 비트(State Bits)**: 각 캐시 라인마다 할당되어 현재 블록의 일관성 상태를 식별하고 상태 머신의 전이 판단 기준으로 활용되는 제어 비트 필드.
- **캐시 제어기(Cache Controller)**: 로컬 CPU 코어의 읽기/쓰기 명령을 처리함과 동시에 공유 버스 인터커넥트에서 수신되는 타 코어의 스누핑 요청을 감지하여 캐시 상태를 전이시키는 하드웨어 제어 로직.
- **스누프 필터(Snoop Filter)**: 각 코어의 사설 캐시가 보유한 라인 목록을 중앙에서 추적하여, 해당 사본을 보유하지 않은 코어로는 스누프 요청이 전파되지 않도록 필터링하는 하드웨어 구조.
- **디렉터리(Directory)**: 메모리 블록별로 현재 해당 사본을 보유 중인 코어들의 공유자 노드 목록과 일관성 상태를 중앙 또는 분산 저장소에 기록 관리하는 구조.

</details>

```text
[캐시 일관성 하드웨어]
├─ 코어별 사설 캐시
│  └─ 캐시 라인
│     ├─ 태그
│     ├─ 데이터 블록
│     └─ 상태 비트
├─ 캐시 제어기
│  ├─ 로컬 요청 처리 경로
│  └─ 스누프 응답 경로
├─ 일관성 인터커넥트
├─ 스누프 필터 또는 디렉터리
└─ 공유 LLC·주기억장치
```

선의 의미: 가지(`├─`)는 소유 관계이며, 캐시 제어기의 두 경로는 로컬 요청과 원격 요청을 각각 담당

| 구성요소 | 책임 |
|:---|:---|
| 캐시 라인 | 태그·데이터·**상태 비트**를 한 단위로 묶어 **소유권** 보관 |
| 상태 비트 | 사본의 수정·읽기·무효 권한 표시 및 전이 판단 입력 제공 |
| 캐시 제어기 | 로컬 요청 발행과 원격 스누프 응답을 수행해 상태 전이 실행 |
| 일관성 인터커넥트 | 버스·링·메시 형태로 요청·무효화·데이터 응답 메시지를 코어 간 전달 |
| **스누프 필터**·**디렉터리** | 사본 보유 위치를 추적해 불필요한 메시지 수신자 제거 |
| 공유 LLC·주기억장치 | 최종 값 보관 및 어느 캐시도 사본이 없을 때 응답 |

#### 한줄 요약
- 상태 비트는 라인마다 몇 비트에 불과하지만 그 비트를 코어 전체에 걸쳐 모순 없이 유지하는 비용이 일관성 하드웨어 대부분을 차지한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **수정(Modified, M)**: 캐시 라인이 단독으로 수정되어 주기억장치와 데이터가 불일치(Dirty)하며, 캐시 라인 축출 시 반드시 메모리로의 되쓰기(Write-Back)가 요구되는 배타적 소유 상태.
- **독점(Exclusive, E)**: 단일 캐시만 사본을 보유하고 주기억장치와 데이터가 일치(Clean)하여, 추가 버스 트랜잭션 없이 곧장 M 상태로 전이해 쓸 수 있는 상태.
- **공유(Shared, S)**: 복수의 캐시가 동일한 클린 사본을 나누어 보유하며, 읽기만 허용되고 쓰기에는 타 캐시 사본의 무효화가 선행되어야 하는 상태.
- **무효(Invalid, I)**: 캐시 라인에 유효한 데이터가 없거나 타 코어의 쓰기 요청으로 사본이 무효화되어, 접근 시 반드시 캐시 미스를 유발하는 상태.
- **버스 트랜잭션(Bus Transaction)**: 캐시 제어기가 일관성 유지를 위해 공유 인터커넥트에 브로드캐스트하는 하드웨어 요청 신호.
- **BusRd**: 읽기용 사본만 요청하는 버스 트랜잭션. 쓰기 권한을 요구하지 않으므로 타 캐시 사본은 무효화되지 않고 S로 남는다.
- **BusRdX**: 읽기와 쓰기 권한을 함께 요청하는 버스 트랜잭션. 타 캐시 사본을 모두 무효화해 단독 소유권을 확보한다.
- **BusUpgr**: 이미 S 사본을 보유한 캐시가 권한만 승격시키는 버스 트랜잭션. 데이터를 다시 받지 않고 무효화 신호만 전파해 BusRdX보다 대역폭을 아낀다.

</details>

```text
[로컬 코어 요청]
 │
 ├ 읽기 · I
 │   └ BusRd 발행
 │       ├ 타 캐시 사본 있음 ── S
 │       └ 타 캐시 사본 없음 ── E
 │
 └ 쓰기
     ├ I ── BusRdX 발행 ─── M
     ├ S ── BusUpgr 발행 ── M
     ├ E ── 버스 트랜잭션 없이 M
     └ M ── M 유지

[원격 스누프 수신]
 │
 ├ BusRd 수신
 │   ├ M 보유 ── 데이터 공급 후 S
 │   └ E·S 보유 ── S 유지
 │
 └ BusRdX·BusUpgr 수신
     └ M·E·S 보유 ── I 무효화
```

분기 결과: 로컬 쓰기는 사본 독점 여부에 따라 **버스 트랜잭션** 발생이 갈리고, 원격 스누프는 요청 종류에 따라 사본을 공급하거나 폐기

#### 한줄 요약
- E 상태가 존재하는 이유는 공유되지 않는 데이터를 읽고 곧바로 쓰는 흔한 패턴에서 버스 트랜잭션 한 번을 통째로 없애기 위함이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **소유(Owned, O)**: MOESI 프로토콜에서 주기억장치에 되쓰지 않은 더티 데이터를 보유한 채 타 캐시의 읽기 공유를 허용하며, 이후 해당 블록 요청의 응답과 최종 되쓰기 책임을 독점하는 상태.
- **전달(Forward, F)**: MESIF 프로토콜에서 여러 클린 공유 사본 중 단 하나의 캐시 라인에만 부여되어 타 코어 읽기 요청의 데이터 응답 책임을 전담하는 상태.
- **개입 전송(Intervention)**: 메모리 왕복 지연을 줄이기 위해 최신 사본을 보유한 이웃 캐시가 요청자 코어에게 데이터를 직접 전달하는 전송 동작.
- **MESI**: Modified, Exclusive, Shared, Invalid의 4가지 상태를 기반으로 동작하는 표준 무효화 기반 캐시 일관성 프로토콜.
- **MESIF**: MESI에 F 상태를 추가해 클린 공유자 간 중복 응답을 없앤 인텔 계열의 확장 프로토콜.
- **MOESI**: MESI에 O 상태를 추가해 더티 데이터를 되쓰지 않고도 코어 간 직접 공유하도록 만든 AMD 계열의 확장 프로토콜.

</details>

| 일관성 프로토콜 | MESI | MESIF | MOESI |
|:---|:---|:---|:---|
| 적용 기준 | 코어 수가 적고 코어 간 공유 자체가 드문 경우 | 클린 공유자가 많아 **개입 전송** 중복 응답이 병목인 경우 | 더티 값 공유가 잦아 되쓰기 트래픽이 병목인 경우 |
| 핵심 특징 | M·E·S·I 4상태로 단독 수정 권한과 클린 공유를 구분 | **F 상태**로 클린 공유자 중 응답자를 하나만 지정 | **O 상태**로 더티 값을 되쓰지 않은 채 공유 허용 |
| 한계 | 더티 사본 요청마다 메모리 되쓰기 왕복 지연 | 이득이 클린 공유에 한정되고 **F 상태** 보유자 이관 규칙 추가 | **O 상태** 보유 코어에 응답·되쓰기 책임 집중 |

#### 한줄 요약
- 세 프로토콜의 추가 상태는 모두 응답 책임을 누구에게 지울지를 정하는 장치이며, 상태를 늘린 만큼 검증해야 할 전이 조합도 함께 늘어난다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **일관성 미스(Coherence Miss)**: 용량이나 충돌이 아닌 타 코어의 쓰기 연산에 따른 캐시 라인 무효화로 인해 발생하는 캐시 미스.
- **거짓 공유(False Sharing)**: 서로 다른 코어가 사용하는 독립된 변수들이 동일한 캐시 라인에 위치하여 불필요한 무효화와 버스 트랜잭션이 반복 발생하는 현상.
- **캐시 라인 핑퐁(Cache Line Ping-Ponging)**: 여러 코어가 동일 캐시 라인을 번갈아 가며 수정함으로써 소유권과 데이터가 코어 간을 지속적으로 왕복하여 심각한 성능 저하를 초래하는 상태.
- **캐시 라인 패딩(Cache-Line Padding)**: 독립적으로 갱신되는 공유 데이터 구조 사이에 여유 공간을 두어 서로 다른 캐시 라인으로 물리 분리하는 소프트웨어 최적화 기법.
- **정형 검증(Formal Verification)**: 수학적 모델링 및 모델 체킹 기법을 통해 도달 가능한 모든 일관성 상태 전이 조합에서 교착 및 SWMR 불변식 위반이 발생하지 않음을 증명하는 검증 방법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 독립 변수가 한 라인에 묶여 **거짓 공유**로 **캐시 라인 핑퐁** 발생 | **캐시 라인 패딩**·코어별 지역 변수 분리 후 최종 합산 | 캐시 크기로 못 줄이는 **일관성 미스** 제거 |
| 더티 사본 요청이 메모리 되쓰기를 거쳐 지연 | **개입 전송** 활용·데이터를 갱신 코어 근처에 배치 | 최신 값 전달 경로 단축 |
| 코어 수 증가로 스누프 브로드캐스트가 인터커넥트 포화 | **스누프 필터** 도입·**디렉터리** 기반으로 전환 | 메시지 수신자를 실제 공유자로 한정해 확장성 확보 |
| 동시 요청 경합 구간에서 전이 누락으로 **SWMR** 위반 | 과도 상태 명시·**정형 검증**과 상태 머신 자동 시험 | 재현 어려운 일관성 버그를 설계 단계에서 차단 |

#### 한줄 요약
- 일관성 비용은 프로토콜 선택이 아니라 데이터 배치가 결정하므로, 어떤 변수를 어느 코어가 쓰는지를 먼저 정리해야 하드웨어 최적화가 효과를 낸다.

## Ⅶ. 결론

- 상태 선택은 공유 패턴이 가르므로 기본 **MESI**에서 출발해 더티 공유가 잦으면 **MOESI**, 클린 공유자가 많으면 **MESIF**로 넓히되, 코어 수가 늘어 스누프 브로드캐스트가 인터커넥트를 포화시키는 지점부터는 상태를 더하는 대신 **디렉터리** 전환으로 메시지 수신 범위부터 좁히는 것이 우선

#### 한줄 요약
- 상태를 늘리는 선택은 공유 패턴이 무엇인지에 답하고, 디렉터리로 옮기는 선택은 코어가 몇 개인지에 답하므로 두 결정은 서로를 대체하지 못한다.
