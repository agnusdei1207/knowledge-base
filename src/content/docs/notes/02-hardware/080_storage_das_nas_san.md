## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다스(Direct Attached Storage, DAS)**: 서버 엉덩이에 선(케이블)을 냅다 꽂아서 디스크를 혼자만 독식하는 1:1 무식한 하드디스크 연결 방식이다.
- **나스(Network Attached Storage, NAS)**: 흔히 쓰는 공유기 랜선에 꽂아서 윈도우, 맥 안 가리고 여러 컴퓨터가 "이 파일 좀 줘" 하고 폴더를 나눠 쓰는 파일 서버이다.
- **샌(Storage Area Network, SAN)**: 돈을 처발라 만든 전용 광케이블 도로망(패브릭)으로, 수십 대의 서버가 거대한 디스크 덩어리를 빛의 속도로 잘라 먹는 고급 스토리지 시스템이다.

</details>

- 정의: 하드디스크를 서버에 어떻게 꽂을 것인지 I/O 단위, 공유 범위, 전송 경로로 구분하는 **다스·나스·샌** 저장 연결 아키텍처
- 배경: 서버 안에 꽂을 수 있는 디스크 개수가 턱없이 모자라서 터져나가는 한계를 박살 내고, 수백 대의 서버가 하나의 거대한 데이터를 씹고 뜯고 공유하기 위함

#### 한줄 요약

- 서버에 직접 꽂아 혼자 쓰면 DAS, 랜선 꽂아 파일 공유하면 NAS, 광케이블 깔아 블록을 나눠 쓰면 SAN이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **블록 레벨 아입출력(Block-Level I/O)**: 파일이 뭔지 신경 안 쓰고, 그냥 하드디스크의 텅 빈 공간(블록)을 서버 맘대로 지지고 볶는 상남자식 접근이다.
- **파일 레벨 아입출력(File-Level I/O)**: 디스크가 어떻게 생겼는지는 모르겠고, 그냥 "내문서\야동.mp4" 달라고 우아하게 파일 경로로 요청하는 방식이다.
- **엔에프에스/에스엠비(NFS/SMB)**: 리눅스(NFS)나 윈도우(SMB) 컴퓨터들이 랜선 위에서 폴더를 공유할 때 쓰는 택배 배송 규칙이다.
- **에프씨/아이스카시(FC/iSCSI)**: 일반 랜선 말고 광케이블(FC)이나 튜닝된 랜선(iSCSI)으로 텅 빈 블록 공간을 무자비하게 쏘아대는 블록 전송 프로토콜이다.

</details>

- 서버가 하드디스크의 멱살을 직접 잡고 빈 공간(LBA)을 자기 맘대로 쪼개 쓰는 무식하고 빠른 **블록 레벨 아입출력** (DAS, SAN)
- 스토리지 장비가 자체 운영체제로 파일을 관리하고, 서버들은 "그 파일 좀 줘" 하고 폴더 통째로 삥 뜯어가는 **파일 레벨 아입출력** (NAS)
- 광케이블(**FC**)이나 이더넷망(**iSCSI**)이 끊어지면 시스템이 뻗어버리니까, 선을 두 개씩 꽂아버리는 다중 경로(Multipathing)를 강제함

#### 한줄 요약

- 디스크 공간을 그냥 날것으로 갖다 쓰면 블록 I/O, 폴더에 담긴 문서를 달라고 하면 파일 I/O 방식이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 버스 어댑터(Host Bus Adapter, HBA)**: 일반 랜카드로는 광케이블을 못 꽂으니까, 서버 등짝에 비싼 돈 주고 따로 다는 광케이블 전용 꽂기 카드이다.
- **에프씨 스위치(FC Switch)**: 인터넷 선 꽂는 스위치허브 말고, 비싼 광케이블(FC)만 꽂아서 SAN 도로망의 교통정리를 해주는 전용 고급 스위치이다.
- **논리 유닛 번호(Logical Unit Number, LUN)**: 하드디스크 수십 개를 묶은 다음, "여기서 100GB는 A 서버 꺼, 200GB는 B 서버 꺼" 하고 피자 조각처럼 잘라서 이름표를 붙인 것이다.

</details>

```text
[ 스토리지 입출력 십자포화 억세스 프레임워크 ]
       [ 호스트 서버 (갑질 요구) ]
                  │
   [ 파일/블록 변환기 (명령어 통역) ]
                  │
[ 직결 / 랜선 / 광케이블 (물리적 배송망) ]
                  │
       [ 스토리지 장비 (데이터 무덤) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 호스트•클라이언트 | "이 파일 내놔!", "이 블록에 덮어써!" 하고 데이터를 무자비하게 요구하는 갑질 서버들 |
| 파일•블록 접근 계층 | **NFS/SMB** 파일 공유 규약을 해독하거나, **SCSI/NVMe** 블록 명령어를 봉투에 싸서 던지는 번역기 |
| 직결•네트워크 경로 | **호스트 버스 어댑터**로 다이렉트 꽂기, 인터넷선(IP) 태우기, 광케이블(**에프씨 스위치**)로 쏘기 등 물리적 배송망 |
| 저장장치•배열 | 하드디스크 수백 개를 묶어서(RAID) 서버마다 쪼개주는(**논리 유닛 번호**) 최종 데이터 무덤 |

#### 한줄 요약

- 서버가 데이터를 요구하면 통역기를 거쳐 선(직결/랜/광)을 타고 스토리지 디스크 조각(LUN)에 꽂힌다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **런 마스킹(LUN Masking)**: B 서버가 A 서버의 피자 조각(LUN)을 훔쳐 먹지 못하게, 스토리지 안에서 "넌 이거 건들지 마" 하고 자물쇠를 채우는 짓이다.
- **조닝(Zoning)**: 에프씨 스위치 단에서 아예 B 서버가 A 서버 쪽 스토리지 포트를 쳐다보지도 못하게 구역을 갈라버리는 깡패 짓이다.

</details>

```text
[ 스토리지 입출력 십자포화 억세스 및 뼈대 결정 흐름 ]
                                 │
                                 ▼
         [ 1. 멱살 판정: 필요한 게 파일이냐, 빈 공간(블록)이냐? ]
             ┌───────────────────┴───────────────────┐
           ( 파일 )                               ( 블록 )
             ▼                                       ▼
          [ NAS ]               [ 2. 독식 판정: 너 혼자 쓸래, 같이 쓸래? ]
                                     ┌───────────────┴───────────────┐
                                ( 혼자 독식 )                   ( 같이 공유 )
                                     ▼                               ▼
                                  [ DAS ]                         [ SAN ]
                                     │                               │
                                     └───────────────┬───────────────┘
                                                     ▼
           [ 3. 방어 떡칠: 다중 경로로 선 안 끊기게 막고, 조닝/마스킹으로 깡패 검증 ]
                                                     │
                                                     ▼
                                            [ 최종 아키텍처 확정 ]
```

### 동작 원리

1. I/O 단위 멱살 판정: 필요한 게 쪼개 쓸 빈 공간(블록)인지, 이미 포장된 문서 파일(파일)인지 1차로 판정함.
2. 공유 범위 판독: 블록일 경우 서버 혼자 독식할 거면 **다스**(DAS), 여러 서버가 뜯어먹을 거면 **샌**(SAN)으로 노선을 가름.
3. 깡패 검증 및 방어: 다중 경로로 선 끊어짐을 막고, 아무나 못 들어오게 **조닝**과 **런 마스킹**으로 철통 보안을 침.
4. 최종 아키텍처 확정: 성능과 예산을 쥐어짜서 스토리지 연결망을 최종 낙점함.

#### 한줄 요약

- 파일이면 NAS, 혼자 쓰는 블록이면 DAS, 여럿이 쓰는 초고속 블록이면 SAN으로 나누고 보안을 걸어라.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다중 경로(Multipathing)**: 광케이블 하나 쥐 파먹었다고 서버가 죽으면 안 되니까, 선을 2~4개씩 꽂아서 한 놈이 죽으면 알아서 다른 선으로 갈아타는 보험 기술이다.

</details>

| 비교 항목 | **다스** (Direct Attached) | **나스** (Network Attached) | **샌** (Storage Area Network) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 그냥 서버 한 대에 하드디스크 무식하게 꽂아서 혼자 다 퍼먹을 시 | 윈도우, 맥, 리눅스 안 가리고 여러 컴퓨터가 폴더 하나 띄워놓고 파일 공유할 시 | 데이터베이스(DB)나 가상머신(VM)처럼 극강의 속도와 수백 대의 서버 연결이 필요할 시 |
| 아키텍처 핵심 구현 특징 | 서버 엉덩이에 선(SAS/SATA) 하나 꽂아서 1:1로만 묶어버리는 폐쇄형 구조 | 일반 랜선(TCP/IP) 꽂아놓고 자체 OS가 파일 시스템을 통째로 관리해 주는 똑똑한 공유형 구조 | 비싼 광케이블(FC)과 전용 스위치로 도배를 해서 디스크 블록을 빛의 속도로 꽂아주는 귀족형 구조 |
| 극복해야 할 태생적 한계점 | 서버 죽으면 데이터도 같이 저세상 가고, 다른 서버랑 용량 공유가 뼛속까지 불가능함 | 사람들이 파일 달라고 미친 듯이 몰려들면 랜선(IP망)이 뻗어서 속도가 개박살 남 | 장비(HBA, 광스위치) 값이 미치도록 비싸고 설정(**조닝**)이 토악질 나올 정도로 복잡함 |

#### 한줄 요약

- 싸고 혼자 쓰면 DAS, 랜선 꽂아 폴더 공유하면 NAS, 비싼 광케이블로 데이터베이스 돌리면 SAN이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **엔브이엠이 오버 패브릭(NVMe over Fabrics, NVMe-oF)**: 랜선이나 광케이블 위로 NVMe SSD의 미친 속도를 그대로 실어 날라서, SAN의 속도를 우주 끝까지 끌어올리는 끝판왕 프로토콜이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사람들이 나스(NAS)에서 동영상 파일 미친 듯이 뽑아 쓰다가 랜선이 꽉 막혀 시스템 전체가 마비되는 재앙 | 일반 랜선 뜯어버리고 텐지(10G) 랜카드로 떡칠한 뒤 링크 집성(LACP)으로 대역폭을 멱살 잡고 늘림 | 좀비 떼처럼 몰려드는 트래픽을 씹어먹고 파일 전송 속도 개박살 절대 방어 |
| 샌(SAN) 광케이블 하나 쥐 파먹었다고 수십억짜리 DB 서버가 통째로 뻗어버리는 어처구니없는 단일 장애 | **다중 경로**(MPIO) 드라이버 깔고 광스위치 2대로 선을 꼬아서 하나 죽어도 알아서 돌아가게 떡칠함 | 선 뽑히고 스위치 터져도 1초 만에 대체 경로로 갈아타서 무중단 서비스 절대 사수 |
| 옆 부서 멍청한 서버가 SAN 스위치에 잘못 붙었다가 우리 DB 디스크 볼륨을 통째로 날려버리는 침범 공격 | 스위치 단에서 **조닝**(Zoning)으로 구역 나누고, 스토리지에서 **런 마스킹**으로 비밀번호 걸어버림 | 인가되지 않은 쓰레기 호스트의 불법 데이터 포맷 공격을 원천 차단해 볼륨 완전 격리 |

#### 한줄 요약

- 랜선 막히면 랜카드 더 꽂고, 선 뽑힐까 쫄리면 선 두 개 꽂고, 남이 내 데이터 건들까 봐 무서우면 조닝과 마스킹을 걸어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스토리지 선택 기준(Storage Architecture Selection Criteria)**: "파일이 필요하냐 빈 공간이 필요하냐?", "서버 혼자 쓸 거냐 다 같이 쓸 거냐?" 하고 따져서 다스, 나스, 샌 중 하나를 고르는 돈지랄 판독기이다.

</details>

- **스토리지 선택 기준** 원칙에 따라, 단일 서버 독식은 **다스**, 다수 시스템 파일 공유는 **나스**, 대용량 고성능 DB/가상화 통합은 **샌** 채택 기조 확립함

#### 한줄 요약

- 혼자 쓰면 DAS, 파일 공유는 NAS, 돈 많고 속도 중요하면 닥치고 SAN을 깔아라.
