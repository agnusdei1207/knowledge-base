## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Edge TPU**: 엣지 환경에서 TensorFlow Lite 모델 추론을 저전력으로 가속하기 위해 Google이 개발한 소형 전용 ASIC.
- **엣지 추론(Edge Inference)**: 데이터가 생성되는 단말 현장에서 클라우드 통신 없이 인공신경망 추론을 직접 수행하는 방식.

</details>

- 정의/개념: TensorFlow Lite INT8 모델 추론을 가속하기 위해 Google이 개발한 **엣지 전용 ASIC 프로세서**
- 배경/필요성: 엣지 단말에서 클라우드 경유 시 발생하는 **네트워크 왕복 지연** 및 프라이버시 침해 위험

#### 한줄 요약
- 구글이 만든 손톱만 한 초저전력 칩으로, 엣지 기기에서 8비트 AI 모델을 초고속으로 추론한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **완전 정수 양자화(Full Integer Quantization)**: 모델의 모든 가중치와 활성화 함수를 INT8 형식으로 변환하여 정수 전용 하드웨어에 맞추는 기법.
- **Edge TPU 컴파일러**: TFLite 모델을 분석하여 가속 가능 서브그래프를 생성하고 전용 기계어로 변환하는 도구.

</details>

- **완전 정수 양자화(INT8)** 기반 고효율 시스톨릭 행렬 연산
- **Edge TPU 컴파일러**를 통한 서브그래프 분할 및 CPU 폴백
- 2W 저전력에서 최대 4TOPS 연산 처리량 실현

#### 한줄 요약
- 8비트 정수 연산 전용 시스톨릭 구조와 자동 서브그래프 분할로 와트당 2TOPS의 고효율을 달성한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TFLite Delegate**: TFLite 런타임이 특정 연산 그래프를 NPU나 Edge TPU 같은 가속기 하드웨어로 위임 실행하는 인터페이스.
- **온칩 메모리(On-chip Buffer)**: 가중치와 피처맵을 보관하여 외부 USB/PCIe 버스 통신을 줄이는 고속 내부 SRAM.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ Google Edge TPU 아키텍처                                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 호스트 인터페이스 (USB 3.0 / PCIe Gen2 / I2C)          │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │ (텐서 데이터 전송)            │
│  ┌──────────────────────────┴────────────────────────────┐  │
│  │ 온칩 SRAM 버퍼 (Weights & Activations Cache)          │  │
│  └───────────┬───────────────────────────┬───────────────┘  │
│              ▼                           ▼                  │
│  ┌───────────────────────┐   ┌───────────────────────┐      │
│  │ 시스톨릭 MAC 어레이   │──>│ 활성화 & 양자화 유닛  │      │
│  │ (INT8 Matrix Engine)  │   │ (ReLU / Scale Unit)   │      │
│  └───────────────────────┘   └───────────┬───────────┘      │
│                                          │                  │
│  ┌───────────────────────────────────────┴───────────────┐  │
│  │ 시퀀서 제어기 (Instruction Sequencer) & DMA           │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트가 모델 텐서를 전달하면 온칩 버퍼를 통해 시스톨릭 MAC 어레이와 활성화 유닛이 연산 후 결과 반환

| 구성요소 | 책임 |
|:---|:---|
| 시스톨릭 MAC 어레이 | INT8 정수 행렬 곱셈 및 2D 컨볼루션 연산을 한 클록 단위로 누산 실행 |
| 온칩 SRAM 버퍼 | 모델 가중치와 중간 특징맵을 내부 저장하여 호스트 버스 트래픽 최소화 |
| 활성화 & 양자화 유닛 | ReLU, Sigmoid 등 활성화 함수 적용 및 출력 정수 스케일링 보정 |
| 시퀀서 제어기 | 컴파일된 Edge TPU 전용 바이너리 명령어를 해석하고 연산 파이프라인 제어 |
| 호스트 인터페이스 | USB 3.0, PCIe, mPCIe를 통해 호스트 CPU와 고속 데이터 송수신 |

#### 한줄 요약
- 시스톨릭 MAC 어레이, 온칩 SRAM, 활성화 유닛, 호스트 I/O가 단일 초소형 패키지에 집적되어 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **대표 데이터셋(Representative Dataset)**: 양자화 보정 시 실제 입력 데이터 분포를 재현하기 위해 사용하는 표본 데이터 집합.

</details>

```text
TensorFlow 모델 학습 완료
      │
      ▼
1. TFLite 변환기: 대표 데이터셋 기반 INT8 완전 정수 양자화
      │
      ▼
2. Edge TPU 컴파일러: 모델 분석 및 가속 가능 서브그래프 추출
      │
      ▼
3. 호스트 CPU: TFLite 런타임 로드 및 Edge TPU Delegate 등록
      │
      ▼
4. Edge TPU: 온칩 SRAM 적재 및 시스톨릭 행렬 추론 연산 가속
      │
      ▼
5. 미지원 연산자 발생 시 CPU 폴백 처리 후 최종 출력 병합
```

**동작 원리**

1. **양자화 변환**: 원본 모델을 대표 데이터셋으로 캘리브레이션하여 완전 INT8 모델로 변환
2. **오프라인 컴파일**: Edge TPU 컴파일러가 모델 그래프를 분석해 전용 서브그래프 바이너리 생성
3. **런타임 위임**: TFLite 런타임이 전용 Delegate를 통해 Edge TPU 드라이버로 서브그래프 전달
4. **하드웨어 가속**: 가중치를 온칩 SRAM에 로드하고 시스톨릭 어레이에서 고속 추론 실행
5. **결과 반환 및 폴백**: 가속 완료 텐서를 호스트로 반환하며 미지원 연산은 CPU가 보완 처리

#### 한줄 요약
- INT8 양자화 → 컴파일러 변환 → 런타임 위임 → 시스톨릭 가속 → 결과 반환 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 엣지 추론 가속기 | Google Edge TPU | 온디바이스 NPU | 엣지 GPU (Jetson) | 엣지 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | INT8 전용 TFLite 모델 저전력 엣지 추론 | 스마트폰·IoT SoC 통합 온칩 가속 | FP16/FP32 복합 AI 모델 및 영상 분석 | 단순 제어 중심 초경량 모델 실행 |
| 핵심 특징 | 극저전력 시스톨릭 어레이 및 모듈형 폼팩터 | SoC 내부 버스 직결 및 초저전력 연산 | 범용 CUDA 생태계 및 다양한 프레임워크 | 높은 유연성 및 별도 가속기 불필요 |
| 한계 | INT8 전용·비지원 연산자 발생 시 CPU 폴백 | 특정 SoC 종속성 및 하드웨어 확장 제약 | 높은 소비 전력(10~30W) 및 발열 | 딥러닝 행렬 연산 처리 속도 극히 느림 |

#### 한줄 요약
- TFLite 정수 추론은 Edge TPU, SoC 통합은 NPU, 복합 정밀도는 GPU, 단순 처리는 CPU를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **경계 텐서(Boundary Tensor)**: 가속기와 CPU 사이에서 서브그래프 분할로 인해 호스트 버스를 왕복해야 하는 중간 데이터.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| INT8 양자화 변환 시 모델 **정확도 저하** | **대표 데이터셋 보정(PTQ)** 및 QAT 재학습 적용 | 정확도 복원 및 추론 가속 성능 확보 |
| 미지원 연산자로 인한 **CPU 폴백 및 통신 지연** | 모델 아키텍처를 Edge TPU 지원 연산자로 재구성 | 단일 서브그래프 100% 가속 및 버스 병목 차단 |
| 소형 밀폐 장치 탑재 시 발열 및 쓰로틀링 | 방열판·서멀 패드 장착 및 추론 프레임 레이트 제한 | 안정적 동작 온도 유지 및 성능 지속 |
| 엣지 장치 무선 업데이트 시 펌웨어 훼손 위험 | **A/B 듀얼 파티션** 및 암호학적 서명 검증 적용 | 무중단 롤백 및 안전한 OTA 배포 보장 |

#### 한줄 요약
- PTQ/QAT로 정확도를 잡고, 지원 연산자로 모델을 재구성해 CPU 폴백을 없애며 방열을 설계한다.

## Ⅶ. 결론

- 초저전력 배터리 기반 엣지 AI 추론은 **Edge TPU**, 복합 정밀도 연산은 **GPU** 선택

#### 한줄 요약
- TensorFlow Lite INT8 양자화와 전용 컴파일러 최적화를 결합하여 엣지 디바이스의 추론 효율을 극대화해야 한다.
