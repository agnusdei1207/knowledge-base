## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Edge TPU**: 엣지 환경에서 TensorFlow Lite 모델 추론을 저전력으로 가속하기 위해 Google이 개발한 소형 전용 ASIC.
- **엣지 추론(Edge Inference)**: 데이터가 생성되는 단말 현장에서 클라우드 통신 없이 인공신경망 추론을 직접 수행하는 방식.

</details>

- 정의/개념: TensorFlow Lite 정수 모델만을 대상으로 삼아 소형 전력 예산에서 **엣지 추론을** 가속하는 **Edge TPU** 전용 ASIC
- 배경/필요성: 클라우드 전송 기반 추론은 네트워크 지연·대역폭 비용·프라이버시 이슈로 **단말 현장 실시간 처리 불가**

#### 한줄 요약
- Edge TPU는 INT8 완전 정수 모델 전용 시스톨릭 연산기를 탑재하여 엣지 디바이스의 극저전력 환경에서 고속 추론을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **완전 정수 양자화(Full Integer Quantization)**: 모델의 모든 가중치와 활성화 함수를 INT8 형식으로 변환하여 정수 전용 하드웨어에 맞추는 기법.
- **Edge TPU 컴파일러**: TFLite 모델을 분석하여 가속 가능 서브그래프를 생성하고 전용 기계어로 변환하는 도구.

</details>

- **완전 정수 양자화** 전제로 부동소수점 회로를 제거하여 극저전력·소형화 달성
- **Edge TPU 컴파일러** 기반 가속 서브그래프 분할 및 전용 바이너리 매핑
- 정수 전용 시스톨릭 데이터 경로 기반 높은 와트당 연산 처리량(4 TOPS @ 2W) 제공

#### 한줄 요약
- 부동소수점 회로를 완전히 배제하고 INT8 정수 연산에만 특화하여 와트당 연산 효율을 극대화한 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TFLite Delegate**: TFLite 런타임이 특정 연산 그래프를 NPU나 Edge TPU 같은 가속기 하드웨어로 위임 실행하는 인터페이스.
- **온칩 메모리(On-chip Buffer)**: 가중치와 피처맵을 보관하여 외부 USB/PCIe 버스 통신을 줄이는 고속 내부 SRAM.

</details>

```text
[Edge TPU]
|-- 호스트 인터페이스 (USB/PCIe)
|-- 온칩 SRAM 버퍼 (가중치·피처맵 보관)
|-- 전용 연산 유닛
|   |-- 시스톨릭 MAC 어레이 (INT8 행렬·컨볼루션)
|   `-- 활성화·양자화 유닛 (ReLU·스케일 보정)
`-- 시퀀서 제어기·DMA (전용 바이너리 해석·파이프라인 제어)
```

선의 의미: 계층 및 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 시스톨릭 MAC 어레이 | INT8 정수 행렬 곱셈 및 2D 컨볼루션 연산을 한 클록 단위로 누산 실행 |
| **온칩 메모리** | 가중치·중간 특징맵 보관으로 호스트 버스 트래픽 최소화 |
| 활성화 & 양자화 유닛 | ReLU, Sigmoid 등 활성화 함수 적용 및 출력 정수 스케일링 보정 |
| 시퀀서 제어기 | 전용 바이너리 명령어 해석과 연산 파이프라인 제어 |
| 호스트 인터페이스 | USB·PCIe 인터페이스를 통한 호스트 CPU와의 텐서 송수신 |

#### 한줄 요약
- 온칩 SRAM 용량이 실행 가능한 모델 크기의 한계를 결정하므로, 컴파일 단계에서 모델 파라미터 최적화가 필수적이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **대표 데이터셋(Representative Dataset)**: 양자화 보정 시 실제 입력 데이터 분포를 재현하기 위해 사용하는 표본 데이터 집합.
- **경계 텐서(Boundary Tensor)**: 가속기와 CPU 사이에서 서브그래프 분할로 인해 호스트 버스를 왕복해야 하는 중간 데이터.

</details>

```text
TensorFlow 모델 학습 완료
        │
   대표 데이터셋으로 보정해 완전 INT8 변환
        │
   Edge TPU 컴파일러가 그래프 분석
        │
   연산자가 가속 대상인가?
   ┌────┴─────┐
  예           아니오
   │             │
전용 바이너리로  호스트 CPU 실행 구간으로 남김
서브그래프 생성    │
   │        경계에서 텐서를 버스로 왕복
 TFLite Delegate가  │
 하드웨어로 위임    │
   │             │
온칩 SRAM 적재 후  │
시스톨릭 어레이 추론 │
   └────┬────────┘
        │
   결과 병합 후 반환
```

#### 한줄 요약
- 모델을 INT8로 완전 양자화한 후 Edge TPU 컴파일러를 거쳐 가속 바이너리로 변환하며, 미지원 연산은 호스트 CPU가 대신 처리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **온디바이스 NPU**: 모바일 SoC 내부에 집적되어 단말의 다양한 AI 기능을 실시간 저전력으로 처리하는 전용 가속기.
- **엣지 GPU (Jetson)**: CUDA 기반의 부동소수점 병렬 연산력을 갖추어 복합 비전 모델을 처리하는 모듈형 GPU.

</details>

| 엣지 추론 가속기 | Google Edge TPU | 온디바이스 NPU | 엣지 GPU (Jetson) | 엣지 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | INT8 전용 TFLite 모델 저전력 엣지 추론 | 스마트폰·IoT SoC 통합 온칩 가속 | FP16/FP32 복합 AI 모델 및 영상 분석 | 단순 제어 중심 초경량 모델 실행 |
| 핵심 특징 | 극저전력 시스톨릭 어레이 및 모듈형 폼팩터 | SoC 내부 버스 직결 및 초저전력 연산 | 범용 CUDA 생태계 및 다양한 프레임워크 | 높은 유연성 및 별도 가속기 불필요 |
| 한계 | INT8 전용·비지원 연산자 발생 시 CPU 폴백 | 특정 SoC 종속성 및 하드웨어 확장 제약 | 높은 소비 전력(10~30W) 및 발열 | 딥러닝 행렬 연산 처리 속도 극히 느림 |

#### 한줄 요약
- Edge TPU는 USB/M.2 모듈 형태로 기존 임베디드 보드에 쉽게 추가하여 저전력 INT8 추론 가속을 구현할 수 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **양자화 인식 훈련(Quantization-Aware Training, QAT)**: 양자화에 따른 오차를 학습 과정에서 미리 보정하여 INT8 정확도 저하를 방어하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정수 양자화 변환 시 모델 인식 정확도 저하 | **양자화 인식 훈련(QAT)** 및 대표 데이터셋 캘리브레이션 | 정확도 복원 및 INT8 가속 성능 유지 |
| 미지원 연산자로 인한 호스트 버스 왕복 병목 | 지원 연산자로 모델 그래프 재구성 및 서브그래프 융합 | **경계 텐서** 전송 지연 및 CPU 폴백 최소화 |
| 소형 밀폐 임베디드 장치 탑재 시 발열 스로틀링 | 서멀 패드 방열 설계 및 동적 추론 주기 제어 | 발열 억제 및 안정적인 연속 동작 보장 |
| 엣지 단말 원격 펌웨어 업데이트 중 훼손 위험 | A/B 이중 파티션 부팅 및 서명 검증 롤백 메커니즘 | 손상 펌웨어 부팅 방지 및 복구성 확보 |

#### 한줄 요약
- Edge TPU 배포 실무는 INT8 QAT를 통한 정확도 보존과 미지원 연산자 제거를 통한 버스 왕복 병목 차단이 핵심이다.

## Ⅶ. 결론

- TFLite 기반 INT8 모델의 초저전력 실시간 현장 추론은 **Edge TPU**를 선택하고, 부동소수점 정밀도나 모델 유연성이 요구되면 **엣지 GPU·범용 NPU** 채택

#### 한줄 요약
- Edge TPU 도입 시 모델의 완전 정수 양자화 수용성과 연산자 100% 가속 지원 여부를 사전에 검증해야 한다.
