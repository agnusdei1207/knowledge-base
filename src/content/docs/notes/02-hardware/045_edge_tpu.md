## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Edge TPU**: Google Cloud TPU 아키텍처를 초소형 임베디드 폼팩터(USB, M.2 모듈)로 경량화하여 현장 온디바이스 추론을 수행하는 저전력 ASIC.
- **현장 추론(Edge Inference)**: 클라우드 연결 없이 데이터가 수집되는 단말 현장에서 즉시 딥러닝 모델을 실행하여 결과를 도출하는 방식.
- **Full Integer Quantization(INT8)**: 부동소수점(FP32) 연산기를 완전히 배제하고 오직 8비트 정수 연산기만을 집적하여 전력과 면적을 극소화하는 기술.

</details>

- 정의/개념: 초소형 에지 단말 및 임베디드 기기에서 TensorFlow Lite 기반 8비트 완전 정수(INT8) 양자화 모델을 초저전력(2W 이하, 4 TOPS)으로 가속하는 Google의 온디바이스 전용 ASIC
- 배경/필요성: 클라우드 서버 전송에 따른 네트워크 왕복 지연(RTT), 데이터 전송 대역폭 비용 및 개인정보 유출 위험을 제거하고, **네트워크 단절 환경에서도 실시간 현장 추론 보장**

#### 한줄 요약

- 8비트 완전 정수(INT8) 전용으로 **초저전력(2W, 4 TOPS) 온디바이스 실시간 추론 실현**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Edge TPU Compiler**: TFLite 모델을 분석하여 칩이 지원하는 연산자를 서브그래프로 추출하고 전용 바이너리를 생성하는 도구.
- **CPU Fallback**: Edge TPU가 지원하지 않는 연산자를 만났을 때 텐서를 Host CPU로 넘겨 대신 실행하는 예외 처리 메커니즘.
- **Device-Transition Cost**: 텐서 데이터가 Edge TPU 칩과 Host CPU 간 PCIe/USB 버스를 오가며 발생하는 전송 지연 오버헤드.

</details>

- 연산기 면적과 전력 소모를 극한으로 억제하기 위해 **8비트 완전 정수(Full Integer INT8)** 모델만 하드웨어 가속
- 칩 내부 가속 가능 연산자만 선별하여 단일 바이너리로 컴파일하는 **Edge TPU 전용 컴파일러** 파이프라인 필수
- 미지원 연산자 조우 시 발생하는 **CPU 폴백(Fallback)** 및 이에 따른 **장치 간 데이터 전송 오버헤드(Device-Transition Cost)** 최소화가 핵심

#### 한줄 요약

- **Full Integer Quantization(INT8)·전용 컴파일러(서브그래프 분할)·CPU 폴백 전송 비용 최소화**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TFLite Runtime**: 모바일 및 임베디드 기기에서 경량화된 딥러닝 모델을 구동하고 Edge TPU 델리게이트(Delegate)를 중계하는 엔진.
- **Edge TPU 코어**: 소형 시스톨릭 배열과 온칩 SRAM으로 구성되어 INT8 행렬 곱셈을 4 TOPS 속도로 쳐내는 하드웨어 유닛.

</details>

```text
[ Edge TPU 배포 및 온디바이스 런타임 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 딥러닝 모델 개발 환경 (TFLite INT8 완전 정수 양자화)        │
└──────────────────────────────┬──────────────────────────────┘
                               │ (edgetpu_compiler)
┌──────────────────────────────┴──────────────────────────────┐
│ Edge TPU 컴파일러 (지원 연산자 서브그래프 분할 및 바이너리)  │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 임베디드 단말 (Raspberry Pi / Coral Dev Board)              │
│  ├─ TFLite 런타임 (Edge TPU Delegate 엔진)                  │
│  │    │                                                     │
│  │    ├── [ 지원 구간 ] ──> [ Edge TPU 코어 (2W, 4 TOPS) ]  │
│  │    │                       ├─ 온칩 SRAM 가중치 버퍼      │
│  │    │                       └─ INT8 시스톨릭 MAC 어레이   │
│  │    │                                                     │
│  │    └── [ 미지원 구간 ] ──> [ Host CPU 폴백 경로 ]        │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: TFLite 모델, Edge TPU 컴파일러, TFLite 런타임, Edge TPU 코어 및 Host CPU 폴백 간의 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 완전 정수 양자화 모델 | 훈련이 끝난 무거운 모델을 소수점을 날려버린 8비트 정수로 잔인하게 압축하여 가벼운 텐서 그래프 및 가중치 파일 껍데기로 제공 |
| 에지 텐서 처리 장치 컴파일러 | 칩이 하드웨어로 돌릴 수 있는 연산을 발라내어 서브그래프 분할을 확정하고, 장치 가속용 전용 바이트코드 기계어 덩어리를 생성 |
| 텐서플로우 라이트 런타임 및 중앙 처리 장치 | 텐서가 칩과 CPU를 오가는 실행 순서를 교통정리 제어하고, 메모리 할당 및 굴욕적인 **중앙 처리 장치 폴백** 실행을 총괄 조정 |
| 에지 텐서 처리 장치 하드웨어 코어 | 칩 한가운데 박혀있는 시스톨릭 곱셈 누산 병렬 연산기 가동 및, 칩 밖으로 나가지 않는 온칩 메모리 데이터 극한 재사용 실행 |

#### 한줄 요약

- **INT8 양자화 모델·Edge TPU 컴파일러·TFLite 런타임·Edge TPU 코어·Host CPU**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Continuous Supported Segment**: 모델 그래프 내에서 NPU가 중간 끊김(CPU 폴백) 없이 100% 연속으로 하드웨어 가속할 수 있는 최적의 레이어 구간.

</details>

```text
[ Edge TPU 현장 추론 실행 및 폴백 처리 흐름 ]
                         │
                         ▼
   [ 1. edgetpu_compiler를 통한 모델 분석 및 서브그래프 분할 ]
                         │
                         ▼
   [ 2. TFLite 런타임이 Edge TPU 전용 컴파일 모델 로드 ]
                         │
        +─────────────────────────────────────────+
        │ 서브그래프 구간별 순차 실행             │
        │              [ Edge TPU 지원 연산? ]    │
        │              /                 \        │
        │          [ 예 ]              [ 아니오 ] │
        │            │                     │      │
        │    3. Edge TPU 칩 가속   4. Host CPU    │
        │    (INT8 시스톨릭 연산)   (폴백 짬처리) │
        │            \                     /      │
        │          5. 경계 텐서 병합 및 다음 레이어│
        +─────────────────────────────────────────+
                         │
                         ▼
   [ 6. 최종 실시간 현장 추론 결과 출력 ]
```

**동작 원리**

1. **컴파일 분할**: 오프라인에서 `edgetpu_compiler`를 실행하여 Edge TPU 지원 서브그래프 생성
2. **모델 로드**: 단말기 TFLite 런타임이 Edge TPU Delegate를 통해 전용 바이너리를 칩 메모리에 적재
3. **칩 가속**: 지원 레이어는 Edge TPU 하드웨어 코어에서 4 TOPS 초고속 INT8 연산 수행
4. **CPU 폴백**: 미지원 특수 연산자 발생 시 경계 텐서를 Host CPU로 넘겨 우회 연산 수행
5. **텐서 병합**: 양쪽의 출력을 융합하여 최종 실시간 현장 추론 완료

#### 한줄 요약

- 컴파일 계획 생성 $\to$ **TFLite 런타임 런치 $\to$ 지원 구간 Edge TPU 가속 $\to$ 미지원 구간 CPU 폴백 $\to$ 텐서 융합**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Edge TPU vs On-Device NPU vs Cloud TPU**:
  - Edge TPU: 외장 모듈(USB/PCIe), INT8 완전 정수 전용, 초저전력(2W)
  - On-Device NPU: 스마트폰 SoC 내장 IP, INT8/FP16 혼합 정밀도, 1~5W
  - Cloud TPU: 데이터센터 서버 랙, BF16/FP32 초거대 분산 학습, 수백 kW

</details>

| 비교 항목 | Edge TPU (Google Coral) | 온디바이스 NPU (스마트폰 SoC) | Cloud TPU (Google Cloud) |
|:---|:---|:---|:---|
| 폼팩터 및 인터페이스 | 외장형 USB 모듈, M.2 / PCIe 카드, 독립 SoC | 모바일 AP(SoC) 내부 온칩 통합 IP 블록 | 데이터센터 서버 랙 및 Pod 클러스터 (광스위치) |
| 지원 정밀도 및 성능 | INT8 완전 정수 전용 (2W, 4 TOPS) | INT8 / INT4 / FP16 혼합 (1~5W, 10~50 TOPS) | BF16 / FP32 / INT8 대규모 가속 (수백 kW Pod) |
| 한계 및 오버헤드 | 부동소수점 미지원, USB/PCIe 버스 전송 오버헤드 | 벤더별 NPU 프레임워크(CoreML, SNPE) 종속 | 네트워크 왕복 지연(RTT), 종량제 클라우드 비용 |

#### 한줄 요약

- 외장형 에지 모듈은 **Edge TPU**, 모바일 SoC는 **NPU**, 초거대 학습은 **Cloud TPU**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Post-Training Quantization (PTQ)**: 대표 보정 데이터셋(Representative Dataset)을 활용하여 FP32 모델을 재학습 없이 고품질 INT8 모델로 변환하는 기법.
- **Atomic Model Swap**: 현장에서 무인 작동 중인 에지 디바이스의 모델 파일을 무중단으로 안전하게 교체하고 이상 시 즉각 롤백하는 펌웨어 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 무거운 소수점을 짓눌러버리는 **완전 정수 양자화** 다이어트 변환 과정에 따른 모델 추론 정확도의 치명적인 박살 및 하락 | 뭉개기 전에 **대표 보정 데이터** 샘플을 집어넣어, 텐서 스케일 팩터의 정교한 영점 조절 최적화 철저 수행 | 부동소수점 대비 크기는 폭풍 감량하면서도 8비트 정수 변환 후 기존 모델 수준의 정확도 손실 완벽 방어 |
| 칩이 모르는 연산자 탓에 잦은 **중앙 처리 장치 폴백**이 빵빵 터지며 발생되는 심각한 핑퐁 텐서 메모리 복사 굼벵이 지연 | 컴파일러가 뱉은 참담한 분석 보고서 검토 후, 모델 코드를 뜯어고치는 **지원 연산자 대체** 꼼수 기법 강제 적용 | 칩 밖으로 나가는 **장치 전환 비용** 오버헤드를 극적으로 박멸하고 칩 안에서의 온칩 하드웨어 연속 가속 100% 달성 |
| 팬(Fan)도 방열판도 없는 초소형 단말 모듈의 섭씨 발열 및 USB 단자의 지속 전력 한도 초과에 따른 칩 화재 또는 뻗음 위험 | 칩이 숨을 고르도록 런타임 추론 듀티 사이클(가동률) 동적 조절 및 주기적인 대기 수면(Sleep) 모드 알고리즘 개입 제어 | 미친 열 폭주 예방을 통한 무인 현장 장비의 지속 가용성 보장 및 싸구려 보드의 전력 공급망 셧다운 안정성 확보 |
| 인터넷이 끊겼다 붙었다 하는 오프라인 에지 환경에서 모델을 원격으로 업데이트하다 파일이 깨져버려 전체 공장이 멈추는 시스템 장애 | 실패 시 흔적이 남지 않는 **원자적 모델 교체** 메커니즘 구축 및 칩이 뻗었을 때 자동 발동되는 **모델 롤백** 로직 펌웨어 내장 | 관리자가 없는 산골짜기 무인 엣지 인프라 환경의 멘탈 붕괴 모델 갱신 안전성 및 공장 100% 무중단 가동률 보장 |

#### 한줄 요약

- **대표 데이터셋 PTQ 보정·연산자 대체(100% 칩 가속)·Duty Cycle 발열 관리·Atomic Rollback 배포**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **Edge TPU 적용 필수 조건**: (1) INT8 양자화 정확도 만족, (2) 연산자 100% Edge TPU 매핑(CPU 폴백 0회), (3) 2W 미만 초저전력 요구 환경.

</details>

- 스마트 팩토리 비전 검사, 드론, 로보틱스 등 **저전력 현장 단말에서 Edge TPU 및 TFLite 완전 정수 파이프라인 표준 채택**

#### 한줄 요약

- **연산자 지원율 100% 확보와 INT8 양자화 정확도 검증**에 기반한 배포 의사결정
