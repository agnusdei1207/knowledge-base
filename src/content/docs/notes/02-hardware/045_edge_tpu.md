## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Edge TPU**: 엣지 환경에서 TensorFlow Lite 모델 추론을 저전력으로 가속하기 위해 Google이 개발한 소형 전용 ASIC.
- **엣지 추론(Edge Inference)**: 데이터가 생성되는 단말 현장에서 클라우드 통신 없이 인공신경망 추론을 직접 수행하는 방식.

</details>

- 정의/개념: TensorFlow Lite 정수 모델만을 대상으로 삼아 소형 전력 예산에서 **엣지 추론**을 가속하는 **Edge TPU** 전용 ASIC
- 배경/필요성: 클라우드 추론은 통신 지연과 연결 단절에 취약하고 원본 데이터를 외부로 내보내야 해, 현장 응답성과 개인정보 보호를 동시에 만족시키지 못함

#### 한줄 요약
- 지원 범위를 정수 모델 하나로 좁힌 것이 성능의 근거이자 도입 장벽이며, 이 칩은 유연성을 포기해 전력 효율을 산 사례다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **완전 정수 양자화(Full Integer Quantization)**: 모델의 모든 가중치와 활성화 함수를 INT8 형식으로 변환하여 정수 전용 하드웨어에 맞추는 기법.
- **Edge TPU 컴파일러**: TFLite 모델을 분석하여 가속 가능 서브그래프를 생성하고 전용 기계어로 변환하는 도구.

</details>

- **완전 정수 양자화** 전제로 부동소수점 회로를 아예 제거
- **Edge TPU 컴파일러**가 가속 가능한 서브그래프만 떼어 내고 나머지는 호스트로 남김
- 정수 전용 데이터 경로로 엣지 전력 예산에서 높은 와트당 처리량 제공

#### 한줄 요약
- 정수 전용이라는 제약이 데이터 경로 전체를 단순하게 만들어 효율을 낳으므로, 이 칩에서 정밀도 타협은 선택이 아니라 입장 조건이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TFLite Delegate**: TFLite 런타임이 특정 연산 그래프를 NPU나 Edge TPU 같은 가속기 하드웨어로 위임 실행하는 인터페이스.
- **온칩 메모리(On-chip Buffer)**: 가중치와 피처맵을 보관하여 외부 USB/PCIe 버스 통신을 줄이는 고속 내부 SRAM.

</details>

```text
[Edge TPU]
├─ 호스트 인터페이스 (USB·PCIe)
├─ 온칩 SRAM 버퍼 (가중치·피처맵 보관)
├─ 연산 유닛
│  ├─ 시스톨릭 MAC 어레이 (INT8 행렬·컨볼루션)
│  └─ 활성화·양자화 유닛 (ReLU·스케일 보정)
└─ 시퀀서 제어기·DMA (전용 바이너리 해석·파이프라인 제어)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 호스트 인터페이스만이 칩 경계를 넘으므로 온칩 SRAM에 담기지 못한 데이터는 모두 이 좁은 통로를 지남

| 구성요소 | 책임 |
|:---|:---|
| 시스톨릭 MAC 어레이 | INT8 정수 행렬 곱셈 및 2D 컨볼루션 연산을 한 클록 단위로 누산 실행 |
| **온칩 메모리** | 가중치·중간 특징맵 보관으로 호스트 버스 트래픽 최소화 |
| 활성화 & 양자화 유닛 | ReLU, Sigmoid 등 활성화 함수 적용 및 출력 정수 스케일링 보정 |
| 시퀀서 제어기 | 전용 바이너리 명령어 해석과 연산 파이프라인 제어 |
| 호스트 인터페이스 | USB·PCIe로 호스트와 텐서 송수신 |

#### 한줄 요약
- 온칩 SRAM 용량이 곧 실행 가능한 모델 크기의 상한이므로, 이 칩의 성능 한계는 연산기가 아니라 메모리 용량이 먼저 정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **대표 데이터셋(Representative Dataset)**: 양자화 보정 시 실제 입력 데이터 분포를 재현하기 위해 사용하는 표본 데이터 집합.
- **경계 텐서(Boundary Tensor)**: 가속기와 CPU 사이에서 서브그래프 분할로 인해 호스트 버스를 왕복해야 하는 중간 데이터.

</details>

```text
TensorFlow 모델 학습 완료
        │
   대표 데이터셋으로 보정해 완전 INT8 변환
        │
   Edge TPU 컴파일러가 그래프 분석
        │
   연산자가 가속 대상인가?
   ┌────┴─────┐
  예           아니오
   │             │
전용 바이너리로  호스트 CPU 실행 구간으로 남김
서브그래프 생성    │
   │        경계에서 텐서를 버스로 왕복
 TFLite Delegate가  │
 하드웨어로 위임    │
   │             │
온칩 SRAM 적재 후  │
시스톨릭 어레이 추론 │
   └────┬────────┘
        │
   결과 병합 후 반환
```

분기 결과: 컴파일 시점에 갈래가 확정되므로 실행 중에는 조정할 수 없고, 경계를 넘는 **경계 텐서**가 호스트 버스를 왕복해 가속 이득을 상쇄할 수 있음

#### 한줄 요약
- **대표 데이터셋**이 실제 입력 분포와 어긋나면 이후 모든 단계가 잘못된 스케일 위에서 돌아가므로, 정확도는 하드웨어가 아니라 이 표본에서 결정된다.

## Ⅴ. 종류 및 비교

| 엣지 추론 가속기 | Google Edge TPU | 온디바이스 NPU | 엣지 GPU (Jetson) | 엣지 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | INT8 전용 TFLite 모델 저전력 엣지 추론 | 스마트폰·IoT SoC 통합 온칩 가속 | FP16/FP32 복합 AI 모델 및 영상 분석 | 단순 제어 중심 초경량 모델 실행 |
| 핵심 특징 | 극저전력 시스톨릭 어레이 및 모듈형 폼팩터 | SoC 내부 버스 직결 및 초저전력 연산 | 범용 CUDA 생태계 및 다양한 프레임워크 | 높은 유연성 및 별도 가속기 불필요 |
| 한계 | INT8 전용·비지원 연산자 발생 시 CPU 폴백 | 특정 SoC 종속성 및 하드웨어 확장 제약 | 높은 소비 전력(10~30W) 및 발열 | 딥러닝 행렬 연산 처리 속도 극히 느림 |

#### 한줄 요약
- 네 가속기 중 Edge TPU만이 외장 모듈이라 기존 장비에 나중에 붙일 수 있으며, 이 확장성이 SoC 통합 NPU 대비 유일한 구조적 우위다.

## Ⅵ. 실무 고려사항 및 대책

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정수 양자화 변환으로 모델 정확도 저하 | 대표 데이터셋 보정 후 필요 시 양자화 인식 재학습 | 정확도 복원과 가속 성능 동시 확보 |
| 미지원 연산자로 폴백과 버스 왕복 지연 발생 | 지원 연산으로 재구성해 서브그래프 경계 축소 | **경계 텐서** 복사와 동기화 횟수 감소 |
| 소형 밀폐 장치 탑재 시 발열 및 쓰로틀링 | 방열판·서멀 패드 장착 및 추론 프레임 레이트 제한 | 안정적 동작 온도 유지 및 성능 지속 |
| 원격 업데이트 중 펌웨어 훼손 위험 | 이중 파티션과 서명 검증·실패 시 롤백 적용 | 손상 이미지 부팅과 복구 불능 위험 완화 |

#### 한줄 요약
- 네 문제 중 둘이 컴파일 이전 단계에서 결정되므로, 배포 후에 손댈 수 있는 여지가 거의 없다는 점이 엣지 가속기 운영의 특징이다.

## Ⅶ. 결론

- 정수 모델의 지원 연산 비율이 높고 전력이 제한되면 **Edge TPU**를 선택하고, 정밀도 요구가 높거나 모델 변경이 잦으면 GPU·범용 NPU의 지연과 전력을 함께 비교

#### 한줄 요약
- 이 칩의 성능은 모델과 짝을 이룰 때만 존재하므로, 도입 검토의 대상은 칩이 아니라 그 칩에서 돌아가는 형태로 바꾼 모델이어야 한다.
