## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **온디바이스 AI(On-Device AI)**: 클라우드 서버와의 통신 없이 스마트폰, 로봇, 차량 등 단말기 자체 하드웨어에서 딥러닝 추론을 독립 실행하는 기술.
- **NPU(Neural Processing Unit)**: 딥러닝 인공신경망의 다차원 텐서 행렬 곱셈(MAC)과 활성화 함수 처리에 특화된 전용 하드웨어 가속기.

</details>

- 정의/개념: 클라우드 통신 없이 단말 안에서 추론을 끝내기 위해 **NPU(Neural Processing Unit)**와 대용량 온칩 메모리를 함께 집적한 **온디바이스 AI(On-Device AI)** 전용 SoC
- 배경/필요성: 클라우드 추론은 연결이 끊기면 기능이 멈추고 원본 데이터를 외부로 보내야 하며 사용량만큼 비용이 계속 발생

#### 한줄 요약
- 이 칩이 파는 것은 연산 성능이 아니라 네트워크에 의존하지 않아도 된다는 성질이며, 그래서 판단 기준도 속도가 아니라 무엇을 단말에 남길지에서 시작한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **에너지 효율(TOPS/Watt)**: 1와트(W)의 전력 소모당 초당 처리 가능한 테라(1조 회) 연산 횟수로, 모바일 NPU 성능의 핵심 지표.
- **DVFS(Dynamic Voltage and Frequency Scaling)**: 부하량과 칩셋 발열 상태에 따라 전압과 클록 주파수를 실시간 조절해 배터리를 아끼는 제어 기술.

</details>

- 연결이 끊긴 환경에서도 추론이 이어지고 원본 데이터의 외부 전송 범위가 줄어듦
- 저비트 정수 연산과 전용 데이터 경로로 높은 **에너지 효율(TOPS/Watt)** 확보
- 냉각 팬이 없는 발열 제약 아래에서 **DVFS(Dynamic Voltage and Frequency Scaling)**로 지속 성능 관리

#### 한줄 요약
- 순간 성능은 열 예산이 허용하는 짧은 구간에서만 나오므로, 이 칩의 실제 능력은 최고 수치가 아니라 몇 분 뒤에도 유지되는 성능으로 재야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **시스톨릭 어레이(Systolic Array)**: 데이터가 2차원 연산기 격자를 심장 박동처럼 규칙적으로 흘러가며 메모리 재접근 없이 행렬 곱을 누적하는 전용 아키텍처.
- **온칩 시스템 캐시(System-Level Cache, SLC)**: 외부 LPDDR DRAM 접근 시 발생하는 막대한 전력 소모를 줄이기 위해 칩 내부에 상주시키는 대용량 SRAM 버퍼.

</details>

```text
[온디바이스 AI SoC]
├─ 호스트 프로세서 (CPU·GPU · 파이프라인 총괄·미지원 연산 대행)
├─ 온칩 인터커넥트
├─ 공유 온칩 시스템 캐시 (재사용 텐서 보관)
└─ NPU 가속기 코어
   ├─ 2D 시스톨릭 MAC 어레이
   ├─ 벡터 활성화·풀링 유닛
   └─ 전력·발열 관리 제어기
```

선의 의미: 가지(`├─`)는 소유 관계이며, 공유 캐시가 호스트와 가속기 사이에 놓여 외부 메모리 접근을 막는 완충 역할

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU·GPU | 파이프라인 총괄과 가속기 미지원 연산 대행 |
| NPU 코어 | **시스톨릭 어레이(Systolic Array)**로 대규모 행렬 연산 전담 |
| **온칩 시스템 캐시(System-Level Cache, SLC)** | 재사용 텐서 보관으로 외부 메모리 접근 전력 감소 |
| 벡터 활성화 엔진 | 비선형 활성화와 정규화 연산 처리 |
| 전력·발열 제어기 | 온도 센서와 연동해 열 예산 안에서 주파수 조절 |

#### 한줄 요약
- 외부 메모리 한 번 읽는 데 드는 전력이 곱셈 수백 번보다 크기 때문에, 이 구조에서 캐시 용량은 성능 부품이 아니라 전력 부품에 가깝다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **그래프 융합(Graph Fusion)**: Conv + BatchNorm + ReLU 등 연속된 복수 연산자를 단일 융합 연산자로 합쳐 메모리 왕복을 없애는 컴파일러 최적화.

</details>

```text
모델 배포 요청 → 양자화·연산자 융합으로 사전 컴파일
        │
   텐서가 온칩 캐시 용량에 들어오는가?
   ┌────┴─────┐
  예           아니오
   │             │
한 번에 적재     타일로 쪼개 순차 적재
   │             (외부 메모리 왕복 증가)
   └────┬────────┘
        │
   연산자를 가속기가 지원하는가?
   ┌────┴─────┐
  예           아니오
   │             │
NPU가 행렬 연산  호스트 코어로 폴백
   │             │
   └────┬────────┘
        │
   온도·전력 예산 초과 시 주파수 하향 후 계속
```

분기 결과: 두 갈림길이 모두 아니오로 가면 외부 메모리 왕복과 코어 간 복사가 겹쳐 가속기가 대부분 놀게 되므로, 성능 저하는 단계적이 아니라 급격하게 나타남

#### 한줄 요약
- **그래프 융합(Graph Fusion)**이 컴파일 단계에 있는 이유는 이후 어떤 실행 최적화도 이미 발생한 메모리 왕복을 되돌릴 수 없기 때문이다.

## Ⅴ. 종류 및 비교

| AI 연산 플랫폼 | 온디바이스 AI SoC (NPU) | 클라우드 서버 GPU | 엣지 전용 DSP/MCU | 온디바이스 FPGA |
|:---|:---|:---|:---|:---|
| 적용 기준 | 스마트폰, 태블릿, 자율주행 ADAS | 데이터센터 초거대 생성형 LLM 학습/추론 | 스마트 워치, 초소형 초저전력 IoT 센서 | 실시간 산업용 비전 및 통신 프로토콜 가속 |
| 핵심 특징 | 저정밀 텐서 가속과 SoC 메모리 공유 | HBM과 범용 저정밀 병렬 연산 | 작은 모델과 신호 처리 중심 | 재구성 데이터 경로와 낮은 지연 변동 |
| 한계 | 메모리 용량 제약(수B 소형 모델에 국한) | 막대한 서버 인프라 비용 및 통신 지연 | 복잡한 딥러닝 트랜스포머 모델 연산 불가 | 높은 칩 단가 및 복잡한 RTL 설계 난이도 |

#### 한줄 요약
- 네 플랫폼은 연산 능력이 아니라 감당 가능한 모델 크기로 갈리며, 단말에서 돌릴 수 있는 모델의 상한은 연산기가 아니라 메모리가 정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **폴백(Fallback)**: NPU 하드웨어가 지원하지 않는 최신 커스텀 레이어를 만났을 때 시스템 크래시 없이 CPU/GPU가 대신 연산하는 안전 메커니즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 미지원 연산자로 **폴백(Fallback)** 지연 발생 | 지원 연산으로 치환·융합해 서브그래프 경계 축소 | 코어 간 텐서 복사와 동기화 횟수 감소 |
| 외부 메모리 대역폭 병목으로 연산기 유휴 | 가중치·중간 상태 양자화와 텐서 타일링 적용 | 품질 검증 범위에서 메모리 이동량 감소 |
| 지속 연산 시 온도 상승으로 성능 급감 | 전압·주파수 제어와 이종 코어 간 부하 분산 | 지속 실효 성능의 안정적 유지 |
| 대형 언어 모델 구동 시 메모리 부족 | 모델 크기·문맥 길이 제한과 중간 상태 양자화 적용 | 메모리 한도 안에서 지연·품질 절충 |

#### 한줄 요약
- 네 문제 중 셋이 메모리에서 비롯되므로, 온디바이스 AI의 세대 경쟁은 연산기 수가 아니라 메모리 용량과 대역폭 위에서 벌어진다.

## Ⅶ. 결론

- 개인정보 보호와 연결성·지연이 중요하고 모델이 단말 메모리에 들어오면 온디바이스 가속기를 쓰고, 큰 모델이나 잦은 갱신이 필요한 부분은 클라우드로 분리하되 판단 기준은 최고 성능이 아니라 종단 지연과 지속 전력

#### 한줄 요약
- 단말과 클라우드는 양자택일이 아니라 기능 단위로 나눌 대상이며, 무엇을 단말에 남길지 정하는 일이 칩 선택보다 먼저 와야 한다.
