## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이퍼바이저(Hypervisor/VMM)**: 깡통 서버 한 대를 쪼개서 가짜 컴퓨터(VM) 수십 대를 띄우고, "넌 CPU 2개 써, 넌 램 4GB 써!" 하고 권력을 휘두르는 가상화 절대 군주이다.
- **타입 1(Type 1, Bare-Metal)**: 윈도우 같은 거 안 깔고, 서버 깡통(하드웨어) 위에 직접 들러붙어서 기계를 다이렉트로 통제하는 뼛속까지 서버용 하이퍼바이저이다.
- **타입 2(Type 2, Hosted)**: 내 노트북 윈도우 위에 알집이나 게임 깔듯이 프로그램 형태로 기생해서 돌아가는, 개발자나 쓰는 얌체 같은 하이퍼바이저이다.

</details>

- 정의: 서버 하드웨어 상의 실행 레이어 위치(Bare-Metal vs Hosted) 및 윈도우 같은 호스트 OS에 기생하느냐 마느냐에 따른 하이퍼바이저 2대 분류인 **Type 1 vs Type 2**
- 배경: 1년 내내 안 끄는 엔터프라이즈 서버(Type 1)와, 그냥 내 노트북에서 잠깐 띄워보는 가상 머신(Type 2)은 요구 성능과 뻗었을 때의 파급력이 완전히 다르기 때문

#### 한줄 요약

- 서버 깡통에 직접 깔면 타입 1(베어메탈)이고, 윈도우 위에 프로그램처럼 깔면 타입 2(호스티드)이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **베어메탈 실행(Bare-Metal Execution)**: 쓰레기 같은 OS 껍데기 다 치워버리고, 하이퍼바이저가 CPU의 최고 권한(특권 모드)을 뺏어서 하드웨어를 직접 패고 조종하는 상남자식 실행이다.
- **호스티드 실행(Hosted Execution)**: 자기가 짱인 줄 알지만 사실은 호스트 윈도우한테 "저 인터넷 좀 쓰게 해주세요" 하고 굽실거리는 유저 프로그램 따위의 신세이다.

</details>

- 윈도우나 리눅스 같은 껍데기(OS) 없이 깡통 기계 위에 바로 올라타서 멱살 잡고 하드웨어를 직결 통제하는 **타입 1 (베어메탈)**
- 기존에 깔려있는 윈도우(호스트 OS) 위에 알집이나 크롬처럼 일반 프로그램(애플리케이션)으로 기생해서 돌아가는 **타입 2 (호스티드)**
- 타입 1은 서버 깡통을 직접 지배하고, 타입 2는 호스트 OS가 뻗으면 가상 머신도 다 같이 저세상 가는 치명적 운명 공동체임.

#### 한줄 요약

- 타입 1은 자원을 다이렉트로 지배하고, 타입 2는 호스트 윈도우한테 얹혀사는(기생하는) 구조이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **게스트 가상 머신(Guest VM)**: 건물주(하이퍼바이저)한테 가짜 CPU랑 가짜 램을 배급받고서, 지가 진짜 컴퓨터인 줄 알고 돌아가는 눈치 없는 가짜 운영체제이다.
- **호스트 운영체제(Host OS)**: 타입 2에서 원래 컴퓨터를 지배하고 있는 진짜 윈도우/맥OS로, 가상 머신들이 싼 똥(I/O 요청)을 대신 치워주는 불쌍한 매개체이다.

</details>

```text
[ 깡통 직결(Type 1) vs 기생충(Type 2) 프레임워크 ]

[ 타입 1 (베어메탈) ]                 [ 타입 2 (호스티드) ]
    [ 가짜 윈도우 (VM) ]                  [ 가짜 윈도우 (VM) ]
           │                                      │
   [ 절대 군주 하이퍼바이저 ]           [ 기생형 하이퍼바이저 프로그램 ]
           │                                      │
[ 깡통 하드웨어 (다이렉트 멱살) ]           [ 찐 윈도우 (호스트 OS) ]
                                                  │
                                          [ 깡통 하드웨어 ]
```

| 구성요소 | 책임 |
|:---|:---|
| 물리 하드웨어 | 가짜 윈도우(VM)들이 빨대 꽂고 파먹을 CPU(VT-x/AMD-V)와 메모리, 랜카드 같은 깡통 자원 |
| **호스트 운영체제** | (Type 2 한정) 자기가 원래 주인인 줄 아는 윈도우/맥OS로, 가상 머신의 똥 닦아주는(드라이버) 역할을 떠맡음 |
| 하이퍼바이저 제어부 | 세입자(VM)들한테 CPU 쪼가리를 배급해 주고 서로 메모리 못 훔쳐보게 멱살 잡고 격리하는 건물주 |
| **게스트 가상 머신** | 건물주한테 자원 구걸해서 돌아가면서, 지가 진짜 컴퓨터인 줄 아는 눈치 없는 가짜 운영체제 |

#### 한줄 요약

- 타입 1은 하이퍼바이저가 기계를 꽉 잡고, 타입 2는 중간에 호스트 OS가 끼어서 통역해 주는 꼬라지이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가상 입출력 패스(Virtual I/O Path)**: 가상 머신이 "하드에 저장해 줘!" 하고 소리쳤을 때, 그게 가짜 디스크를 거쳐 진짜 하드디스크까지 도달하는 배달 경로이다.

</details>

```text
[ 하이퍼바이저 배치 계층 및 입출력 십자포화 분기 흐름 ]
                                 │
                                 ▼
   [ 1. 요청 접수: 가상 머신이 "하드디스크 쓸게!" 하고 가짜 요청 냅다 던짐 ]
                                 │
                 ┌───────────────┴───────────────┐
            ( 타입 1 장비 )                 ( 타입 2 장비 )
                 ▼                               ▼
       [ 2. 하이퍼바이저가 직접 ]        [ 3. 찐 윈도우한테 짬처리 ]
       [ 하드디스크 드라이버 구동 ]      [ (시스템 콜로 굽실굽실 통역) ]
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
       [ 4. 물리 I/O 폭격: 진짜 하드디스크에 데이터가 쾅쾅 박히고 작업 끝! ]
```

### 동작 원리

1. 가짜 장치 요청 접수: 세입자(**게스트 가상 머신**)가 "나 하드디스크 좀 쓸게!" 하고 가짜 요청을 냅다 던짐.
2. 갈림길 분기(Type 1): 건물주(하이퍼바이저)가 직접 깡통 하드디스크 드라이버를 조종해서 빛의 속도로 꽂아버림.
3. 짬처리 분기(Type 2): 건물주가 힘이 없어서 찐 주인(**호스트 운영체제**)한테 "이것 좀 디스크에 써주세요" 하고 굽실거리며 시스템 콜(System Call)을 넘김.
4. 진짜 I/O 쾅쾅: 어떻게든 물리 장치(진짜 하드디스크)에 도달해서 데이터가 쾅쾅 박히고 작업이 끝남.

#### 한줄 요약

- 타입 1은 지가 알아서 다이렉트로 꽂고, 타입 2는 호스트 OS 눈치를 보면서 한 단계 거쳐서 꽂는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **브이엠엠 오버헤드(VMM Overhead)**: 진짜 기계에서 돌리면 1초면 될 걸, 굳이 가상 머신에서 돌려서 1.2초가 걸리게 만드는 0.2초의 빡치는 성능 깎임 현상이다.

</details>

| 비교 항목 | **타입 1** (Bare-Metal Hypervisor) | **타입 2** (Hosted Hypervisor) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 아마존(AWS)이나 기업 전산실처럼 서버 1만 대 띄워놓고 1년 내내 안 끄는 엔터프라이즈 환경 | 그냥 내 맥북이나 윈도우 PC에서 리눅스 잠깐 띄워서 숙제나 테스트할 때 |
| 아키텍처 핵심 구현 특징 | 윈도우 따위 안 깔고 기계 깡통에 직접 하이퍼바이저를 박아 넣어서 CPU를 100% 쥐어짜 냄 | 윈도우 깔고 그 위에 알집 깔듯이 가상 머신 프로그램을 깔아서 얌체같이 기생함 |
| 극복해야 할 태생적 한계점 | 전용 서버 장비(드라이버)가 아니면 아예 설치조차 안 되는 극강의 까탈스러움 | 메인 윈도우(호스트 OS)가 파란 화면 뜨고 뻗으면 안에 켜둔 가상 머신도 싹 다 즉사함 |
| 대표 제품 | **VMware ESXi**, **Xen**, **Microsoft Hyper-V**, **KVM** | **VMware Workstation**, **Oracle VirtualBox** |

#### 한줄 요약

- AWS나 찐 서버는 무조건 타입 1(ESXi, KVM)이고, 내 방 PC에서 돌리면 타입 2(VirtualBox)이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가상 시피유 초과 할당(vCPU Overcommit)**: 진짜 CPU 코어는 10개밖에 없는데, 가상 머신들한테는 "너네 다 4개씩 줄게!" 하고 가짜로 뻥튀기(40개)해서 팔아먹는 폰지 사기이다.
- **단일 루트 입출력 가상화(Single Root I/O Virtualization, SR-IOV)**: 10기가짜리 비싼 랜카드 하나를 가상 랜카드 수십 개로 쪼개서, 가상 머신들 엉덩이에 다이렉트로 꽂아버리는 끝판왕 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **타입 2** 쓰다가 메인 윈도우가 뻗어서 안에 있던 DB 가상 머신 10대가 다 같이 저세상 가는 대참사 | 돈지랄해서 상시 운영 서버는 무조건 깡통에 직접 박는 **타입 1**(베어메탈)로 싹 다 갈아엎음 | 빌어먹을 호스트 OS 붕괴로 인한 동반 자살(장애 경계) 원천 차단 |
| 가짜 CPU를 너무 많이 뻥튀기(**가상 시피유 초과 할당**)해서 VM들이 "내 차례 언제 와!" 하고 줄 서다 시스템이 멈춤 | CPU Ready 지연 시간을 칼같이 감시하고 뻥튀기(오버커밋) 비율에 무자비한 상한선 가이드라인 떡칠 | 가상 머신들이 버벅대고 멈추는 끔찍한 반응 지연(Latency) 완벽 억제 |
| 가상 머신들이 랜카드 쓸 때마다 하이퍼바이저가 통역해 주느라 서버 CPU가 100% 치솟고 터지려 함 | 물리 랜카드 하나를 가짜 수십 개로 찢어서 VM에 직빵으로 꽂아주는 **단일 루트 입출력 가상화(SR-IOV)** 장착 | 통역하느라 낭비되던 CPU 부하를 씹어먹고 랜카드 속도를 극한으로 쥐어짬 |

#### 한줄 요약

- 뻗으면 안 되는 서버는 타입 1 박고, CPU 뻥튀기 사기는 적당히 치고, 랜카드 병목은 SR-IOV로 뚫어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **하이퍼바이저 선택 기준(Hypervisor Type Selection Criteria)**: 이 가상 머신이 1년 내내 살아서 돈을 벌어다 주는 놈인지, 내일 지워버릴 장난감인지 따져보고 타입 1/2를 쳐바르는 기준표이다.

</details>

- **하이퍼바이저 선택 기준** 원칙에 따라, 24시간 안 끄는 엔터프라이즈 서버는 **타입 1**, 개인 노트북 개발 환경은 **타입 2** 채택 기조 확립함

#### 한줄 요약

- 돈 버는 진짜 서버는 타입 1, 혼자 개발하며 장난치는 PC는 타입 2를 깔아라.
