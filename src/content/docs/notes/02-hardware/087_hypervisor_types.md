## 미리 알고가기

- **하이퍼바이저(Hypervisor)**: 물리 자원을 가상머신별로 배정·격리
- **중앙처리장치(Central Processing Unit, CPU)**: VM 명령을 실행하는 물리 연산 자원
- **운영체제(Operating System, OS)**: 프로세스·메모리·장치 관리
- **가상머신(Virtual Machine, VM)**: 가상 자원에서 게스트 OS 실행
- **입출력(Input/Output, I/O)**: VM과 물리 장치 간 데이터 경로
- **Type 1 하이퍼바이저**: 하드웨어에서 VM을 직접 관리
- **Type 2 하이퍼바이저**: 호스트 OS 프로세스로 VM 실행
- **베어메탈·호스티드(Bare-metal·Hosted)**: 베어메탈은 하드웨어 위에서 직접 실행하는 Type 1, 호스티드는 호스트 OS 위에서 실행하는 Type 2 구조
- **시스템 호출·드라이버(System Call·Driver)**: 시스템 호출은 응용이 OS 서비스를 요청하는 인터페이스이고 드라이버는 OS 요청을 장치 명령으로 변환함
- **장애 경계(Failure Domain)**: 한 구성요소의 장애가 함께 영향을 미치는 시스템 범위
- **서버 통합(Server Consolidation)**: 여러 서버 작업을 소수 물리 서버의 VM으로 모아 자원 사용률을 높이는 방식
- **프라이빗 클라우드(Private Cloud)**: 한 조직이 전용으로 운영하며 가상 자원을 서비스 형태로 제공하는 클라우드 환경

## Ⅰ. 개요

- 정의/개념: Type 1의 하드웨어 직접 실행과 **Type 2의 호스트 OS 실행 계층**
- 기존 한계: 단일 배치 방식은 **운영 격리·호스트 장치 재사용** 동시 충족에 한계

### 쉽게 이해하기 (학습용)

- 컴퓨터를 켜자마자 가상머신을 관리할지 기존 운영체제 안에서 관리할지 나누는 방식이다.

## Ⅱ. 특징

- **하이퍼바이저 실행 위치**가 I/O 경로·장애 범위 결정
- Type 1은 **호스트 OS 없는 직접 자원 중재** 제공
- Type 2는 **호스트 OS 드라이버·도구 재사용** 제공

### 쉽게 이해하기 (학습용)

- 관리 계층이 아래에 있으면 장치를 직접 다루고 위에 있으면 기존 운영체제의 장치를 빌려 쓴다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid

    subgraph S[서버 가상화 경계]

        H -->|Type 2 호스트 부팅| O

        V -->|가상 자원| G
    end
```

| 설계 요소 | 입력·상태 | 역할 |
|:---|:---|:---|
| 물리 하드웨어 | CPU·메모리·장치 상태 | VM 실행 자원 제공 |
| 호스트 OS | Type 2 장치·시스템 서비스 | 드라이버·파일·화면 기능 제공 |
| 하이퍼바이저 | VM 구성·자원 정책 | 자원 배정·명령 중재·격리 |
| 게스트 VM | 가상 CPU·메모리·장치 | 게스트 OS·응용 실행 |

> 요약: Type 1은 하드웨어, Type 2는 호스트 OS에 배치

### 쉽게 이해하기 (학습용)

- Type 1은 하드웨어 바로 위에 있고 Type 2는 기존 운영체제 위에 한 층 더 올라간다.

## Ⅳ. 운영 고려사항

| 운영 위험 | 대응 | 기대 효과 |
|:---|:---|:---|
| Type 1 관리 계층 취약점이 전체 VM에 영향 | 관리망 분리·최소 서비스·신속한 패치 | 공격면·장애 범위 축소 |
| Type 2 호스트 OS 부하·장애가 VM에 전파 | 호스트 자원 예약과 절전·업데이트 정책 통제 | 시험 환경 안정성 향상 |
| 과도한 자원 초과 할당으로 VM 경합 | CPU 준비 시간·메모리 회수·I/O 지연 감시 | 서비스 품질 유지 |
| 스냅숏·이미지 난립으로 복구 불확실 | 수명주기·버전·무결성·복구 시험 관리 | 운영 일관성 확보 |

### 쉽게 이해하기 (학습용)

- VM이 장치를 쓸 때 Type 1은 바로 중재하고 Type 2는 기존 운영체제를 한 번 더 거친다.

## Ⅴ. 종류 및 비교

| 하이퍼바이저 유형 | Type 1 | Type 2 |
|:---|:---|:---|
| 적용 기준 | 서버 통합·**상시 운영** | 개발·시험·**장치 재사용** |
| 핵심 특징 | 하드웨어에서 **VM 자원 직접 중재** | 호스트 OS 프로세스로 **VM 실행** |
| 한계 | 드라이버 호환·**관리 복잡성** | 호스트 장애·**추가 I/O 경로** |

> 요약: 운영은 Type 1, 개발·검증은 Type 2

### 쉽게 이해하기 (학습용)

- 계속 운영할 서버에는 Type 1, 개인 개발·시험에는 Type 2를 선택한다.

## Ⅵ. 실무 사례

1. 프라이빗 클라우드는 **Type 1**으로 서버 자원 통합

### 쉽게 이해하기 (학습용)

- 회사 클라우드는 서버 자원을 나눠 쓰려고 Type 1을 설치한다.

## Ⅶ. 결론

- 가상화 환경의 격리·성능·운영 편의성을 확보하기 위해 **호스트 OS 의존성·장치 접근·공격면·배포 목적**을 검토하고, 서버 통합은 Type 1, 데스크톱 시험은 Type 2 하이퍼바이저를 선택한다

### 쉽게 이해하기 (학습용)

- 서버를 계속 운영하면 Type 1, 기존 컴퓨터에서 시험하면 Type 2를 선택한다.
