## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **하이퍼바이저**: 물리 자원을 가상머신별로 배정하고 서로 격리하는 제어 계층이다.
- **장애 경계**: 한 구성요소의 장애가 함께 영향을 미치는 시스템 범위이다.
- **VM(Virtual Machine)**: 격리된 가상 하드웨어에서 게스트 운영체제를 실행하는 시스템이다.

</details>

- 정의/개념: 실행 위치에 따라 직접형•호스트형으로 나눈 **VM 자원 중재 계층**
- 배경/필요성: 단일 배치로는 **상시 격리•호스트 장치 재사용 동시 최적화 곤란**

#### 한줄 요약

- **하이퍼바이저 실행 위치**에 따른 Type 1•Type 2 구분

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **Type 1 하이퍼바이저**: 하드웨어 위에서 직접 실행하며 가상머신 자원을 중재하는 방식이다.
- **Type 2 하이퍼바이저**: 호스트 운영체제의 프로세스로 실행되며 그 드라이버와 도구를 이용하는 방식이다.
- **OS(Operating System)**: 하드웨어 자원을 관리하고 응용 실행 환경을 제공하는 운영체제이다.
- **I/O(Input/Output)**: 처리기와 장치 사이에서 데이터나 제어 신호를 주고받는 입출력 동작이다.

</details>

- **하이퍼바이저 실행 위치**가 I/O 경로•장애 범위 결정
- Type 1은 **호스트 OS 없는 직접 자원 중재** 제공
- Type 2는 **호스트 OS 드라이버•도구 재사용** 제공

#### 한줄 요약

- **직접 자원 중재•호스트 OS 재사용**의 배치 차이

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **게스트 VM(Guest VM)**: 가상 하드웨어에서 운영체제와 응용을 실행하는 구성이다.
- **하이퍼바이저(Hypervisor)**: VM별 물리 자원 배정과 격리를 중재하는 구성이다.
- **호스트 OS(Host OS)**: Type 2에서 프로세스•메모리•장치 서비스를 제공하는 구성이다.
- **물리 하드웨어(Physical Hardware)**: CPU•메모리•장치의 실제 실행 자원을 제공하는 구성이다.

</details>

```text
          [게스트 VM]
               |
         [하이퍼바이저]
           /          \
 Type 1 직접          Type 2 매개
       /                \
[물리 하드웨어] ----- [호스트 OS]
```

선의 의미: 게스트 VM은 하이퍼바이저 위에 있고, 하이퍼바이저가 하드웨어에 직접 접하면 Type 1, 호스트 OS를 함께 매개하면 Type 2인 정적 배치 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 물리 하드웨어 | **VM 실행 자원 제공** |
| 호스트 OS | **드라이버•서비스 제공** |
| 하이퍼바이저 | **자원 중재•격리** |
| 게스트 VM | **운영체제•응용 실행** |

#### 한줄 요약

- **Type 1 직접 배치•Type 2 호스트 매개 배치**

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **가상 장치 레지스터**: 게스트가 장치 명령과 상태를 읽고 쓰는 가상 입출력 인터페이스이다.
- **가상 장치 큐**: 게스트가 장치 명령과 버퍼 위치를 기록하는 대기열이다.
- **시스템 호출(System Call)**: 응용이 운영체제의 장치 서비스를 요청하는 인터페이스이다.
- **드라이버(Driver)**: 운영체제 요청을 물리 장치 명령으로 변환하는 소프트웨어이다.

</details>

```text
[게스트 가상 I/O 디스크립터]
              │
              ▼
1. 가상 장치 요청 해석
              │
              ▼
2. I/O 실행 경로 선택
       ┌──────┴────────┐
       │ Type 1        │ Type 2
       ▼               ▼
[하이퍼바이저 드라이버] [호스트 시스템 호출]
       │               │
       │        3. 호스트 드라이버 변환
       │               │
       └───────┬───────┘
               ▼
4. 물리 I/O 실행
               │
               ▼
      [가상 I/O 완료 반환]
```

**동작 원리**

1. **가상 장치 요청 해석**: 레지스터•큐의 게스트 명령 확인
2. **I/O 실행 경로 선택**: Type 1 직접 또는 Type 2 매개 경로 결정
3. **호스트 드라이버 변환**: Type 2 요청을 물리 명령으로 변환
4. **물리 I/O 실행**: 장치 처리 후 가상 완료 상태 생성

#### 한줄 요약

- **Type 1 직접 I/O•Type 2 호스트 매개 I/O** 경로

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **베어메탈**: 하드웨어에서 직접 실행하는 Type 1 가상화 구조이다.
- **호스티드**: 호스트 운영체제 위에서 실행하는 Type 2 가상화 구조이다.
- **서버 통합**: 여러 서버 작업을 소수 물리 서버의 가상머신으로 모아 자원 사용률을 높이는 방식이다.

</details>

| 하이퍼바이저 유형 | Type 1 | Type 2 |
|:---|:---|:---|
| 적용 기준 | 서버 통합•**상시 운영** | 개발•시험•**장치 재사용** |
| 핵심 특징 | 하드웨어에서 **VM 자원 직접 중재** | 호스트 OS 프로세스로 **VM 실행** |
| 한계 | 드라이버 호환•**관리 복잡성** | 호스트 장애•**추가 I/O 경로** |

> 요약: 상시 서버 운영은 **Type 1**, 개발•검증은 **Type 2** 선택

#### 한줄 요약

- **상시 운영•개발 시험**에 따른 Type 1•Type 2 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **CPU(Central Processing Unit)**: 명령 실행과 시스템 자원 제어를 담당하는 중앙 처리 장치이다.
- **가상 중앙 처리 장치(Virtual CPU, vCPU)**: VM에 할당되어 물리 CPU 시간으로 실행되는 논리 처리기이다.
- **CPU 준비 시간**: vCPU가 실행 가능하지만 물리 CPU 할당을 기다린 시간이다.
- **메모리 회수**: 호스트가 가상머신에 할당한 미사용 메모리를 되찾는 동작이다.
- **스냅숏**: 특정 시점의 가상머신 디스크와 실행 상태를 보존한 복구 기준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Type 1 관리 계층 취약점이 모든 VM으로 **장애 전파** | **관리 인터페이스 분리•최소 서비스•신속 패치** | **공격면•장애 경계** 축소 |
| Type 2 호스트 OS 부하•재시작이 **VM 중단** 유발 | **호스트 자원 예약•업데이트 시간 통제** | **시험 VM 가용성** 향상 |
| 자원 초과 할당으로 vCPU•메모리 **경합 증가** | **CPU 준비 시간•메모리 회수 감시** | **VM 응답 지연** 억제 |
| 스냅숏•이미지 난립으로 **복구 시점 불확실** | **스냅숏 수명주기•무결성•복구 시험** | **복구 버전 일관성** 확보 |

#### 한줄 요약

- **Type 1 관리면 최소화•Type 2 호스트 자원 통제**

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **공격면**: 공격자가 접근하거나 악용할 수 있는 인터페이스와 기능의 범위이다.
- **상시 운영**: 서비스 중단을 최소화하며 지속적으로 시스템을 제공해야 하는 운영 조건이다.

</details>

- 상시 서버는 **Type 1**, 개발•시험은 **Type 2** 선택

#### 한줄 요약

- **상시 서버 운영**은 Type 1, 기존 OS 기반 시험은 Type 2 선택
