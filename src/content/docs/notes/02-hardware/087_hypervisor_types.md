## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이퍼바이저(Hypervisor / VMM)**: 단일 물리 서버의 하드웨어 컴퓨팅 자원(CPU, 메모리, 스토리지, 네트워크)을 가상화하여 다수의 독립된 가상 머신(VM)을 생성, 스케줄링, 격리 통제하는 가상화 관리 계층.
- **베어메탈(Bare-Metal)**: 호스트 운영체제(Windows, Linux)의 개입 없이 물리 서버 하드웨어 실리콘 위에 하이퍼바이저가 직접 설치되어 하드웨어를 직접 제어하는 실행 환경.

</details>

- 정의/개념: 가상 머신 모니터(VMM)의 물리 하드웨어 상주 위치와 기저 운영체제 개입 여부에 따라 **Type 1(베어메탈)**과 Type 2(호스티드)로 분류하는 **가상화 아키텍처 모델**
- 배경/필요성: 단일 물리 서버에 단일 OS 배치 시 발생하는 서버 자원 유휴화(평균 활용률 10~15%) 및 서비스 장애 도메인 격리 부재 한계 극복

#### 한줄 요약
- 하드웨어 직결형 Type 1(베어메탈)과 호스트 OS 기반 Type 2(호스티드)로 구분되어 엔터프라이즈 성능과 데스크톱 편의성을 차별화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **장애 도메인(Failure Domain)**: 특정 소프트웨어 계층(호스트 OS 또는 단일 VM)에서 장애가 발생했을 때 그 영향이 시스템 전체로 파급되는 물리적·논리적 범위.
- **이중 스케줄링(Double Scheduling)**: Type 2 환경에서 게스트 OS 스케줄러와 호스트 OS 커널 스케줄러가 2중으로 CPU 타임슬라이스를 중복 조율하여 발생하는 지연.

</details>

- Type 1 베어메탈 직결: 하이퍼바이저가 호스트 OS 없이 물리 하드웨어 실리콘 위에서 직접 구동되어 네이티브 대비 95~99%의 고성능 및 강력한 결함 격리성 제공
- Type 2 호스티드 추상화: 범용 운영체제(Windows, Linux) 상단에서 일반 프로세스 애플리케이션으로 동작하여 설치와 관리가 용이하나 **이중 스케줄링** 및 다단계 I/O 오버헤드 수반
- **장애 도메인** 차별화: Type 1은 특정 게스트 VM 장애가 타 VM에 전파되지 않으나, Type 2는 기저 호스트 OS 장애 발생 시 전체 게스트 VM이 동시 다운되는 종속적 구조

#### 한줄 요약
- Type 1은 중간 OS 없이 하드웨어에 직결되어 엔터프라이즈급 성능을 내며, Type 2는 호스트 OS 위에서 동작하여 개발 편의성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **게스트 VM(Guest Virtual Machine)**: 하이퍼바이저가 할당한 vCPU, vRAM, vDisk를 기반으로 독립 실행되는 가상 운영체제 인스턴스.
- **호스트 OS(Host Operating System)**: Type 2 환경에서 물리 하드웨어를 직접 제어하며 하이퍼바이저 프로세스에 CPU/메모리 자원을 할당하는 기저 OS.

</details>

```text
+-------------------------------------------------------------+
|               Type 1 Hypervisor (Bare-Metal)                |
|  +---------------------------+  +------------------------+  |
|  | Guest VM 1 (Kernel/Apps)  |  | Guest VM N (Kernel/Apps)  |
|  +---------------------------+  +------------------------+  |
|  +-------------------------------------------------------+  |
|  | Bare-Metal Hypervisor / VMM (ESXi / KVM / Xen)        |  |
|  +-------------------------------------------------------+  |
|  | Physical Server Hardware (CPU, MMU, NIC, Storage)    |  |
+-------------------------------------------------------------+

+-------------------------------------------------------------+
|               Type 2 Hypervisor (Hosted)                    |
|  +---------------------------+  +------------------------+  |
|  | Guest VM 1 (Kernel/Apps)  |  | Guest VM N (Kernel/Apps)  |
|  +---------------------------+  +------------------------+  |
|  | Hosted Hypervisor App (VirtualBox, Workstation)       |  |
|  +-------------------------------------------------------+  |
|  | Host Operating System (Windows / Linux Kernel)        |  |
|  +-------------------------------------------------------+  |
|  | Physical Server Hardware (CPU, MMU, NIC, Storage)    |  |
+-------------------------------------------------------------+
```

선의 의미: 실선 박스는 하이퍼바이저 아키텍처별 계층 경계를 나타내며 내부 블록은 가상 머신, 하이퍼바이저 제어 계층 및 기저 운영체제의 적층 구조를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| Type 1 베어메탈 VMM | 하드웨어 직접 상주 및 VM 자원 스케줄링·결함 격리 |
| Type 2 호스티드 VMM | 호스트 OS 시스템 콜 변환 및 개발 편의성 인터페이스 제공 |
| 게스트 가상 머신(VM) | 독립된 vCPU/vRAM 상에서 수정 없는 OS 커널 및 앱 구동 |
| 호스트 운영체제 | Type 2 환경의 물리 자원 할당 및 기저 하드웨어 드라이버 구동 |
| 물리 하드웨어 계층 | CPU, MMU(EPT), I/O 디바이스 등 실제 실리콘 컴퓨팅 자원 제공 |

#### 한줄 요약
- Type 1은 중간 OS 없이 물리 서버에 직결되고, Type 2는 범용 호스트 OS 위에서 프로세스 형태로 중계 실행된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가상 I/O 패스(Virtual I/O Path)**: 게스트 VM 내부 드라이버가 발생시킨 읽기/쓰기 명령이 물리 스토리지 컨트롤러에 도달하기까지의 계층별 처리 경로.
- **vCPU 스케줄링**: 하이퍼바이저가 게스트의 가상 CPU 스레드를 물리 CPU 코어의 시분할 타임슬라이스에 맵핑하여 실행시키는 프로세스.

</details>

```text
[게스트 애플리케이션 I/O 쓰기 요청 인입]
           │
           ▼
[1. 게스트 OS 가상 디스크 드라이버 I/O 요청 발행]
           │
           ▼
     <하이퍼바이저 유형 판정>
           │
     ┌─────┴─────┐
     │           │
[Type 1 베어메탈] [Type 2 호스티드]
     │           │
     │           ▼
     │    [2. 가상 I/O를 호스트 OS 시스템 콜로 변환]
     │           │
     │           ▼
     │    [3. 호스트 OS 커널 및 파일시스템 드라이버 경유]
     │           │
     ▼           ▼
[4. 물리 스토리지 컨트롤러 데이터 커밋]
           │
           ▼
[5. 하이퍼바이저 가상 인터럽트 주입 및 I/O 완료]
```

분기 결과: Type 1은 하이퍼바이저가 물리 드라이버로 1단계 직결 커밋하여 초저지연을 달성하며, Type 2는 호스트 OS 시스템 콜 및 파일시스템을 거치는 3단계 중계로 오버헤드가 발생함

**동작 원리**:
1. 게스트 애플리케이션 파일 쓰기 시 게스트 OS 커널 가상 블록 디바이스 드라이버의 I/O 요청 패킷 생성.
2. Type 1 환경 내 베어메탈 하이퍼바이저 가로채기 및 내장 네이티브 스토리지 드라이버 기반 하드웨어 직결 전송.
3. Type 2 환경 내 호스티드 VMM 프로세스의 게스트 가상 I/O 명령 해석 및 기저 호스트 OS 시스템 콜(write) 변환 호출.
4. 호스트 OS 커널 스케줄러 및 파일시스템 계층 경유 기반 최종 물리 디스크 컨트롤러 대상 3단계 중계 전달.
5. 물리 하드웨어 쓰기 완료 시 컨트롤러 인터럽트 수신 하이퍼바이저의 게스트 VM 대상 가상 인터럽트 주입 및 트랜잭션 완료.

#### 한줄 요약
- Type 2는 호스트 OS의 파일시스템과 드라이버를 그대로 빌려 쓰는 대가로 I/O마다 한 계층을 더 지나고, Type 1은 그 계층을 걷어낸 대신 전용 하드웨어와 운영 체계를 전제로 요구한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로VM(MicroVM)**: AWS Firecracker처럼 서버리스 FaaS 환경을 위해 불필요한 레거시 디바이스 모델을 제거하고 5ms 이내로 초고속 기동하는 경량 VM.
- **OS 컨테이너(OS Container)**: 별도 게스트 OS 없이 호스트 OS 커널의 네임스페이스와 cgroups를 공유하여 밀리초 단위로 격리 프로세스를 배포하는 기술.

</details>

| 대상 구분 | Type 1 (Bare-Metal) | Type 2 (Hosted) | OS 컨테이너 (Docker) | 마이크로VM (MicroVM) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 대규모 엔터프라이즈 IaaS 클라우드 및 고성능 격리 환경 시 | 개인 데스크톱 개발·테스트 및 이종 OS 간이 실습 환경 시 | 동일 OS 커널 기반 초경량·고밀도 마이크로서비스 배포 시 | 초고속 콜드스타트(10ms 이내) 요구 서버리스 FaaS 환경 시 |
| 핵심 특징 | 하드웨어 직결 가상화 계층, 네이티브 대비 95~99% 성능, 수십 초 부팅, 하드웨어 수준 최고 보안 격리 | 호스트 OS 상단 애플리케이션, 네이티브 대비 70~85% 성능, 수십 초 부팅, 호스트 OS 종속 중간 보안 격리 | OS 커널 공유 격리, 네이티브 대비 99% 이상 성능, 수백 ms 초고속 부팅, 호스트 커널 공유로 낮은 보안 격리 | 초경량 KVM 하드웨어 가상화, 네이티브 대비 98% 이상 성능, 5~10ms 초고속 부팅, 하드웨어 수준 최고 보안 격리 |
| 한계 | 전용 하드웨어 요구 및 복잡한 설치·운영 | 호스트 OS 종속성 및 성능 저하 | 커널 공유로 인한 다중 테넌트 격리 취약 | 미니멀 설계로 레거시 장치 호환성 제약 |

#### 한줄 요약
- 엔터프라이즈 IaaS는 Type 1, PC 개발은 Type 2, 클라우드 네이티브 MSA는 컨테이너, 서버리스 FaaS는 MicroVM을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CPU 레디 타임(CPU Ready Time, %RDY)**: vCPU가 실행 준비를 마쳤으나 하이퍼바이저로부터 물리 CPU 코어를 할당받지 못하고 대기열에서 지연되는 시간 비율(권장 5% 미만).
- **클러스터 HA(High Availability)**: 물리 서버 장애 감지 시 가상 머신을 정상 동작 중인 타 물리 서버 노드로 즉시 자동 페일오버 재기동시키는 고가용성 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 vCPU 오버커밋으로 인한 성능 저하 | **CPU 레디 타임(%RDY < 5%)** 모니터링 및 할당 조정 | 스케줄러 대기열 정체 해소 및 성능 균일화 |
| Type 1 스토리지/네트워크 I/O 병목 발생 | **SR-IOV** 패스스루 및 **Virtio** 드라이버 적용 | 하이퍼바이저 오버헤드 90% 제거 및 I/O 가속 |
| 물리 서버 하드웨어 장애 시 전체 VM 동시 중단 | 하이퍼바이저 **클러스터 HA** 자동 페일오버 구성 | 장애 시 타 물리 노드로 무중단 자동 재기동 |

#### 한줄 요약
- 실무에서는 %RDY 모니터링으로 CPU를 관리하고, SR-IOV로 I/O를 가속하며, 클러스터 HA로 물리 장애를 방어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SmartNIC/DPU 오프로드**: 가상 스위칭, 네트워크 패킷 암호화, 스토리지 입출력 등 하이퍼바이저 호스트 CPU 부하를 전용 SoC 기반 스마트 카드(DPU)로 이전시키는 기술.
- **Firecracker**: Rust 언어로 작성된 최소형 가상 머신 모니터로, Linux KVM을 활용하여 단일 서버에서 수천 개의 격리된 서버리스 람다 함수 인스턴스를 초고속 구동하는 MicroVM VMM.

</details>

- 엔터프라이즈 IaaS 클라우드는 하드웨어 직결형 Type 1(KVM, ESXi)이 지배적 표준이며 데스크톱 개발 환경은 Type 2(VirtualBox)가 양분해왔으나, 최근 클라우드 네이티브 환경에서는 서버리스 FaaS를 위한 **마이크로VM**(Firecracker) 및 DPU 기반 **하이퍼바이저** 오프로드(SmartNIC 기반 베어메탈 가상화)로 진화하고 있으므로, 아키텍처 설계자는 워크로드의 격리 수준과 성능 목표에 맞춰 최적의 가상화 계층 선정 필수.

#### 한줄 요약
- 하이퍼바이저는 엔터프라이즈 성능과 보안을 위한 Type 1과 개발 편의성을 위한 Type 2로 명확히 구분하여 설계해야 한다.
