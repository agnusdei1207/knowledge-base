## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **3-상태 버퍼(Tri-State Buffer)**: 논리 High('1'), 논리 Low('0') 외에 전기적으로 선로와 분리되는 고임피던스(High-Z) 상태를 출력하여 복수의 장치가 단일 버스를 공유하게 하는 논리 회로.
- **고임피던스(High-Impedance, High-Z)**: 출력단이 전기적으로 단절(Open)되어 버스에 전류를 흘리거나 흡수하지 않는 무구동 절연 상태.
- **버스 경합(Bus Contention)**: 두 개 이상의 드라이버가 동일 버스 라인에 서로 다른 전압(High와 Low)을 동시 인가하여 과도 단락 전류가 흐르고 소자가 파손되는 현상.

</details>

- 정의/개념: 논리 High('1'), 논리 Low('0') 외에 전기적으로 선로와 분리되는 고임피던스(High-Z) 상태를 출력하여 복수의 장치가 단일 버스를 공유하게 하는 디지털 논리 게이트
- 배경/필요성: 다수의 칩이 동일한 물리 버스에 연결될 때 발생하는 **전기적 단락(Bus Contention)을 방지하고 양방향 버스 핀 수 절감**

#### 한줄 요약

- 0, 1 외에 **전기적 절연 상태인 고임피던스(High-Z)**를 지원하여 버스 공유 실현

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Output Enable(OE)**: 버퍼 출력을 활성화할지 또는 High-Z 절연 상태로 둘지를 결정하는 1비트 제어 신호.
- **Bus Turnaround Time**: 이전 드라이버가 High-Z로 완전히 빠져나간 뒤 다음 드라이버가 구동을 시작할 때까지의 안전 데드타임(Dead Time).
- **Floating (부동 상태)**: 모든 드라이버가 High-Z 상태일 때 선로 전압이 결정되지 않아 외부 노이즈에 취약해지는 상태.

</details>

- 비선택 장치의 출력을 **고임피던스(High-Z)**로 전환하여 단일 물리 신호선의 안전한 시분할 공유 보장
- 소자 파손(Contention)을 방지하기 위한 제어 로직의 **OE 상호 배타성** 및 충분한 **Bus Turnaround Time** 확보 필수
- 모든 출력이 High-Z일 때 발생하는 **Floating(부동) 노이즈**를 방지하기 위해 풀업/풀다운 저항 또는 Bus Hold 셀 장착

#### 한줄 요약

- **Output Enable(OE) 상호 배타성·High-Z 절연·Bus Turnaround Time** 준수

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CMOS 푸시풀 출력단(Push-Pull Output)**: PMOS와 NMOS를 상하로 배치하여 OE가 비활성화되면 두 트랜지스터를 모두 Off시켜 High-Z를 형성하는 회로.
- **Bus Hold Cell**: 버스가 High-Z 상태일 때 직전의 논리 상태를 약한 피드백으로 유지하여 스위칭 전력 낭비를 막는 회로.

</details>

```text
[ 3-상태 버퍼 반도체 논리 회로 및 공유 버스 구조도 ]
               전원 전압 (VDD)
                  │
              ┌───┴───┐
      데이터 ─┤ P-MOS │ (OE=0 비활성화 시 완전 차단)
              └───┬───┐
                  ├───┼─── 출력 ──> [ 시스템 공유 데이터 버스 ] ──┐
              ┌───┴───┐                                          │
      데이터 ─┤ N-MOS │ (OE=0 비활성화 시 완전 차단)            │
              └───┬───┘                             ┌──────────┴──────────┐
                  │                                 │ 풀업 바이어스 저항  │
                 접지                               └──────────┬──────────┘
                                                               │
                                                           전원 전압 (부동 방지)
```

선의 의미: Output Enable(OE) 신호에 따른 CMOS 출력단 및 풀업 저항/Bus Hold 회로 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 출력 활성화 핀 (OE) | 데이터를 보낼 구동 상태와 전기를 끊을 고임피던스 절연 상태 선택 통제 |
| 상보성 금속 산화막 반도체 출력단 | 핀이 활성화되었을 때 논리 영과 일의 강력한 물리적 전압 쏘아내기 구동 |
| 바이어스 저항 (Pull-up) | 버스가 무구동 절연 상태일 때 부동하지 않도록 안전한 기본 논리 상태 고정 |
| 버스 유지 회로 (Bus Hold) | 약한 피드백을 통해 직전 버스가 가졌던 마지막 논리 상태 지속 유지 및 노이즈 차단 |

#### 한줄 요약

- **OE 제어 핀·CMOS 푸시풀 출력단·풀업 저항(Floating 방지)·Bus Hold 회로**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Shoot-Through Current**: 2개의 3-상태 버퍼가 동시에 켜져 전원에서 접지로 대전류가 단락되는 현상.

</details>

```text
[ 양방향 공유 버스 쓰기/읽기 전환 흐름 ]
                      │
                      ▼
   [ 1. 호스트 드라이버 OE=1 활성화 및 쓰기 데이터 구동 ]
                      │
                      ▼
   [ 2. 쓰기 완료 후 호스트 OE=0 전환 (High-Z 진입) ]
                      │
                      ▼
   [ 3. 충돌 방지를 위한 Bus Turnaround Time 대기 (Dead Time) ]
                      │
                      ▼
   [ 4. 타겟 메모리 칩 OE=1 활성화 및 읽기 데이터 구동 ]
```

**동작 원리**

1. **쓰기 구동**: 호스트가 OE를 활성화하여 공유 버스에 데이터 전압(0 또는 1)을 강력하게 인가
2. **High-Z 전환**: 쓰기가 끝나면 즉시 호스트의 OE를 비활성화하여 출력을 High-Z 절연 상태로 전환
3. **데드타임 대기**: 두 칩 간의 동시 켜짐을 방지하기 위해 정해진 버스 전환 시간 동안 버스 무구동 유지
4. **읽기 구동**: 메모리 칩이 자신의 OE를 켜고 안전하게 읽기 데이터를 버스로 전송

#### 한줄 요약

- 마스터 쓰기 구동 $\to$ **OE 끄기(High-Z) $\to$ Bus Turnaround 대기 $\to$ 슬레이브 읽기 구동**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Tri-State Buffer vs MUX vs Open-Drain**:
  - Tri-State: 3상태(0, 1, High-Z), 칩 외부 양방향 버스용
  - MUX: 2상태(0, 1), 칩 내부 온칩 인터커넥트 표준
  - Open-Drain: 2상태(0, High-Z), 풀업 저항 필요, I2C/인터럽트 유선 논리합(Wired-OR)

</details>

| 비교 항목 | 3-상태 버퍼 (Tri-State Buffer) | 멀티플렉서 (MUX) | 오픈 드레인 (Open-Drain / Open-Collector) |
|:---|:---|:---|:---|
| 물리 출력 상태 | 3가지 상태 (High, Low, High-Z) | 2가지 논리 상태 (High, Low) | 2가지 상태 (Low, High-Z) |
| 주 적용 영역 | 칩 외부 보드 레벨 양방향 공유 버스 (GPIO, DRAM 버스) | 칩 내부(SoC 온칩) 데이터 경로 선택 및 멀티플렉싱 | 유선 논리합(Wired-OR), I2C 버스, 공유 인터럽트 라인 |
| 한계 및 위험 | 제어 충돌 시 단락 전류(Contention) 발생, Floating 노이즈 | 칩 내부 면적 소모(AND/OR 게이트 증가), 단방향 신호 | 풀업 저항 충전 지연(RC 시상수)으로 인한 속도 한계 |

#### 한줄 요약

- 외부 양방향 버스는 **3-상태 버퍼**, 온칩 내부는 **MUX**, 공유 인터럽트는 **오픈드레인**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ODT(On-Die Termination)**: 고속 양방향 버스에서 신호 반사파(Reflection)를 억제하기 위해 칩 내부에 동적 종단 저항을 구성하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제어 신호가 미세하게 어긋나 두 구동기가 동시에 켜지며 불꽃이 튀는 **순간 단락** 파손 | 칩 레벨의 엄격한 **출력 활성화 상호 배타** 디코더 삽입 및 비중첩 전환 간격 강제 할당 | 칩을 태워버리는 과도 전류 방지 및 출력단 충돌 파손 원천 예방 |
| 공유 버스 상의 모든 출력이 절연으로 빠질 때 노이즈가 폭포수처럼 유입되는 **부동 현상** | 물리적 버스 핀에 풀업 저항 달기 또는 **버스 유지 회로** 하드웨어 셀 내부 탑재 | 부동 상태의 노이즈 완벽 차단 및 요동치는 스위칭 전력 소모 극적 절감 |
| 칩 내부 설계 코드에서 버퍼 선언 시 반도체 합성 오류 및 테스트 불가 늪에 빠짐 | **논리 합성** 단계에서 칩 내부 배선은 안전한 **멀티플렉서** 구조로 설계 도구 강제 전환 | 생산 후 칩 불량 테스트 검증성 확보 및 내부 신호 단락 위험 100% 무결성 보장 |
| 초고속 양방향 버스 구동 시 선 끝단 반사파로 인한 심각한 데이터 왜곡 및 오인식 | **온 다이 터미네이션** 기술을 칩 내부에 심어 양방향 전환 시마다 동적 임피던스 매칭 자동 적용 | 고주파 핀 신호의 찌그러짐을 펴서 무결성을 보장하고 초고속 안정적 데이터 전송 달성 |

#### 한줄 요약

- **OE 상호 배타성 보장·Pull-up/Bus Hold(부동 방지)·온칩 MUX 대체·ODT(반사파 제거)**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **현대 반도체 설계 표준**: ASIC/SoC 내부에서는 High-Z 상태 검증 및 DFT(Design for Testability) 난제로 인해 3-상태 버퍼 사용을 금지하고 순수 MUX 트리를 표준으로 강제.

</details>

- 칩 외부 버스는 **3-상태 버퍼 + ODT/Bus-Hold**, 칩 내부(ASIC/FPGA)는 **MUX 기반 내부 상호 연결 표준 채택**

#### 한줄 요약

- **물리적 핀 수 제약(외장 3-상태)과 회로 무결성(온칩 MUX)**을 구분한 최적 설계
