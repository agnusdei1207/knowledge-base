## Ⅰ. 개요

**물리 큐비트(physical qubit)**는 실제 하드웨어 소자에 구현된 큐비트다. 제어·측정 오류, 결맞음 손실, 누설, 다른 큐비트와의 간섭에 노출된다. **논리 큐비트(logical qubit)**는 여러 물리 큐비트와 반복 오류 정정 절차를 이용해 하나의 양자 정보를 부호화한 추상 연산 단위다.

논리 큐비트의 목적은 오류를 없애는 것이 아니라, 목표 알고리즘이 허용하는 수준까지 논리 오류 확률을 낮추는 것이다. 필요한 물리 자원은 선택한 부호, 물리 오류 모델, 코드 거리, 측정·복호 속도, 논리 게이트 방식에 따라 크게 달라진다.

#### 한줄 요약

- 물리 큐비트는 오류가 있는 소자이고, 논리 큐비트는 오류 정정으로 목표 신뢰도를 얻으려는 부호화 단위다.

## Ⅱ. 특징

- **부호화**: 논리 상태는 여러 데이터 큐비트에 분산되며, 보조 큐비트가 오류 증후군을 반복 측정한다.
- **코드 거리**: 코드 거리 $d$는 논리 오류를 일으키는 최소 오류 사슬의 길이를 나타내는 지표다. 이상적인 독립 오류 가정에서 정정 가능한 오류 수와 관계가 있다.
- **논리 오류율**: 물리 오류율이 적절한 조건을 만족하고 복호가 정확할 때 거리 증가로 낮아질 수 있다. 실제 감소율은 하드웨어·오류 모델·회로에 의존한다.
- **고전 제어 의존성**: 증후군 수집, 복호, Pauli frame 추적, 피드백이 논리 연산의 일부다.

#### 한줄 요약

- 논리 성능은 물리 큐비트 수만이 아니라 코드 거리, 오류 특성, 고전 복호·제어의 결합 결과다.

## Ⅲ. 구조 및 구성요소

```text
논리 연산 인터페이스
        │
오류 정정 코드 패치
 ├─ 데이터 큐비트: 논리 상태 부호화
 └─ 측정 큐비트: 안정자 증후군 획득
        │
증후군 스트림 → 고전 복호기 → Pauli frame·피드백
````n`n선의 의미: 가지(`├─`, `└─`)는 소유·연결 관계; 화살표(`→`, `▼`)는 데이터 또는 제어 흐름 방향

| 구성요소 | 역할 |
|:---|:---|
| 물리 큐비트 | 실제 상태 준비·게이트·측정이 이뤄지는 하드웨어 단위다. |
| 데이터 큐비트 | 논리 상태를 분산 부호화한다. |
| 측정 큐비트 | 데이터 상태를 직접 읽지 않고 안정자 정보를 측정한다. |
| 복호기 | 증후군과 오류 모델로 보정·프레임 정보를 추론한다. |
| Pauli frame | 즉시 물리 보정을 생략하고 알려진 반전 정보를 논리 연산·판독에 반영한다. |
| 논리 게이트 프로토콜 | 부호화된 상태 사이의 연산을 fault-tolerant하게 구현한다. |

표면 코드의 단일 패치가 곧 하나의 완전한 범용 논리 큐비트 자원은 아니다. 데이터·측정 패치 외에도 논리 게이트, 측정, 상태 준비, 통신·라우팅, 매직 상태 정제 자원이 필요할 수 있다.

#### 한줄 요약

- 논리 큐비트는 부호화 패치와 복호기뿐 아니라 논리 연산·보조 자원을 포함하는 시스템 개념이다.

## Ⅳ. 동작 흐름

```text
알고리즘의 논리 게이트·목표 성공 확률 정의
        ↓
전체 실패 예산에서 논리 오류 예산 배분
        ↓
물리 오류·측정·복호 특성으로 코드·거리·자원 산정
        ↓
반복 증후군 측정과 고전 복호·프레임 추적
        ↓
논리 게이트·판독의 실제 오류를 검증하고 자원 조정
````n`n선의 의미: 가지(`├─`, `└─`)는 소유·연결 관계; 화살표(`→`, `▼`)는 데이터 또는 제어 흐름 방향

**실패 예산**은 알고리즘 전체 성공률 요구를 각 논리 연산·메모리·측정 단계에 나눠 허용 오류를 정하는 방법이다. 특정 알고리즘 이름이나 고정 게이트 수로 계산할 수 없으며, 회로 최적화·병렬성·하드웨어 오류·정제 프로토콜을 포함해 산정한다.

#### 한줄 요약

- 논리 큐비트 수요는 먼저 알고리즘 실패 예산을 세운 뒤 실제 물리 오류와 부호 자원으로 환산한다.

## Ⅴ. 비교

| 비교 항목 | 물리 큐비트 | 논리 큐비트 |
|:---|:---|:---|
| 단위 | 실제 소자와 제어·판독 채널 | 여러 물리 큐비트와 QEC 절차가 만든 추상 상태 |
| 오류 | 개별 게이트·측정·환경 오류에 직접 노출 | 부호·복호 조건에서 더 낮은 논리 오류를 목표로 함 |
| 자원 | 소자 수, 제어선, 냉각·광학 등 | 데이터·측정 큐비트, 복호, 논리 게이트·정제 자원 포함 |
| 연산 한계 | 장치 오류와 결맞음·제어에 제한 | 오류 정정이 성공해도 유한한 논리 오류와 자원·시간 비용 존재 |
| 검증 | 물리 오류 특성화·캘리브레이션 | 논리 오류, 복호 지연, 종단 간 알고리즘 성공률 |

논리 큐비트는 물리 큐비트와 완전히 독립된 “가상 소자”가 아니다. 계속되는 물리 게이트·측정과 고전 제어가 이를 유지한다.

#### 한줄 요약

- 물리 큐비트는 기반 자원이고, 논리 큐비트는 그 자원·오류 정정의 성능을 논리 연산 관점에서 표현한 단위다.

## Ⅵ. 실무 고려사항 및 대책

| Problem | Countermeasure | Effect |
|:---|:---|:---|
| 물리 오류·상관 오류가 코드 가정과 맞지 않음 | 게이트·측정·누설·공통 모드 오류를 실측하고 코드·매핑·하드웨어 개선에 반영 | 논리 오류 추정의 신뢰도 향상 |
| 논리 게이트, 특히 비클리포드 연산의 자원이 큼 | 매직 상태 정제·대체 프로토콜·회로 최적화의 시간·공간 비용을 함께 산정 | 숨은 자원 병목 파악 |
| 복호 지연이 측정 주기·피드백을 따라가지 못함 | 스트리밍 복호, 지연 예산, Pauli frame 관리와 제어 경로 검증 | 오류 정정 운영 가능성 향상 |
| 명목 논리 큐비트 수만으로 프로젝트 규모를 판단 | 데이터 패치, 라우팅, 상태 공장, 예비 자원, 시스템 인프라를 포함해 산정 | 과소 설계 위험 완화 |

#### 한줄 요약

- 논리 큐비트 계획은 부호화 숫자보다 물리 오류·복호·논리 게이트·보조 자원을 모두 포함해야 한다.

## Ⅶ. 결론

논리 큐비트는 긴 양자 알고리즘을 위한 핵심 목표지만, 자동으로 무오류·무제한 실행을 제공하지 않는다. 현재 장치에서 물리 오류와 측정이 충분히 제어되고 목표 논리 오류 예산을 달성할 수 있을 때 QEC 자원 투자를 검토한다. 제한된 실험에서는 물리 큐비트의 품질 개선과 오류 완화를 병행하며, 논리 자원 산정은 알고리즘·하드웨어 변화에 따라 반복 갱신한다.

#### 한줄 요약

- 논리 큐비트의 가치는 숫자 자체가 아니라 목표 연산을 위한 검증된 논리 오류율과 전체 자원 비용에 있다.
