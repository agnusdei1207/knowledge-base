## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **물리 큐비트(Physical Qubit)**: 실제 초전도 소자나 이온 트랩 챔버에 하드웨어로 제작된 개별 큐비트 소자로, 외부 노이즈와 결맞음 손실에 직접 노출됨.
- **논리 큐비트(Logical Qubit)**: 다수 물리 큐비트와 반복 신드롬 측정으로 오류를 목표 수준까지 억제한 부호화 연산 단위.

</details>

- 정의/개념: 다수 **물리 큐비트(Physical Qubit)** 활용 오류 정정 부호로 묶어 더 낮은 오류율을 갖는 **논리 큐비트(Logical Qubit)** 기반 합성하는 연산 체계
- 배경/필요성: 물리 큐비트 하나로는 게이트를 수십 단만 쌓아도 상태가 무너져, 의미 있는 알고리즘을 끝까지 실행할 수 없음

#### 한줄 요약
- 두 개념이 나뉘어 있다는 사실 자체가 현재 하드웨어의 한계를 보여 주며, 물리 큐비트 수를 성능으로 읽는 보도가 오해를 부르는 지점이기도 하다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **결함 허용 양자 컴퓨팅(FTQC)**: 구성요소 오류가 생겨도 논리 오류가 통제된 범위에 머물도록 연산·측정·복호를 설계한 체계.
- **매직 상태 증류(Magic State Distillation)**: 범용 양자 연산에 필수적인 $T$-게이트를 결함 허용 방식으로 실행하기 위해 고순도 보조 양자 상태를 정제하는 프로세스.

</details>

- 물리 오류가 임계치 아래이면 코드 거리를 늘려 논리 오류율을 지수적으로 억제
- **오버헤드 비율(Overhead Ratio)** 부호와 목표 오류율에 따라 급격히 증가
- **매직 상태 증류(Magic State Distillation)** 기반 부호가 직접 지원하지 못하는 게이트 자원 공급

#### 한줄 요약
- 정정 부호가 모든 게이트를 똑같이 싸게 만들어 주지 않으며, 일부 게이트만 유독 비싸다는 비대칭이 알고리즘 설계를 실제로 지배한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **오버헤드 비율(Overhead Ratio)**: 하나의 논리 큐비트를 보호하기 위해 요구되는 데이터 큐비트 및 신드롬 측정 보조 큐비트의 총 물리적 수량.

</details>

```text
[논리 큐비트 합성 계층]
├─ 알고리즘 계층
│  └─ 논리 큐비트 연산 (하드웨어를 모르는 추상 단위)
├─ 오류 정정 미들웨어
│  ├─ 표면 코드 패치 (코드 거리에 따라 크기 결정)
│  ├─ 신드롬 패리티 측정
│  ├─ 실시간 복호기·파울리 프레임
│  └─ 매직 상태 팩토리 (특수 게이트용 자원 정제)
└─ 물리 하드웨어 계층
   ├─ 물리 데이터 큐비트
   └─ 물리 보조 큐비트
```

선의 의미: 가지(`├─`)는 소유 관계이며, 알고리즘 계층은 아래 두 계층의 존재를 모른 채 논리 단위로만 기술

| 구성요소 | 책임 |
|:---|:---|
| 물리 데이터 큐비트 | 칩 상에서 중첩 상태를 분산 보관 |
| 물리 보조 큐비트 | 주기적 패리티 측정으로 오류 신드롬 추출 |
| 오류 정정 엔진 | 코드 거리에 따라 다수 물리 큐비트를 논리 패치로 묶음 |
| 매직 상태 팩토리 | 특수 게이트에 투입할 고순도 보조 상태 정제 |
| 논리 게이트 실행기 | 패치 병합·분할로 논리 큐비트 간 얽힘 구현 |

#### 한줄 요약
- 매직 상태 팩토리가 별도 구성요소로 존재한다는 사실은 정정 부호가 범용 연산을 그 자체로 지원하지 못한다는 뜻이며, 이 결핍이 자원 산정의 큰 축을 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **격자 수술(Lattice Surgery)**: 인접한 표면 코드 패치들의 경계 안정자를 함께 측정하여 물리적 이동 없이 두 논리 큐비트 간 CNOT 연산을 수행하는 기법.

</details>

```text
알고리즘 컴파일 → 논리 회로 정의
        │
   목표 논리 오류율에 맞는 코드 거리로 패치 할당
        │
   연산 중에도 보조 큐비트가 신드롬을 계속 측정
        │
   실행할 게이트가 부호에서 직접 지원되는가?
   ┌────┴─────┐
  예           아니오
   │             │
패치 병합·분할로  매직 상태 팩토리에서
논리 게이트 수행  정제된 자원을 주입
   │             │
   └────┬────────┘
        │
   복호 결과를 파울리 프레임에 누적 반영
        │
   최종 측정값을 마지막 신드롬과 함께 복호해 논리 비트 확정
```

분기 결과: 지원되지 않는 게이트 하나가 팩토리 전체를 요구하므로 자원 비용이 게이트 종류에 따라 자릿수 단위로 갈리며, 컴파일 목표도 게이트 수가 아니라 그 게이트 수를 줄이는 쪽이 됨

#### 한줄 요약
- **격자 수술(Lattice Surgery)** 물리적 이동 없이 얽힘을 만드는 덕분에 평면 하드웨어에서도 논리 연산이 성립하며, 이 기법이 없으면 2차원 배치는 곧 한계가 된다.

## Ⅴ. 종류 및 비교

| 양자 정보 연산 계층 | 논리 큐비트 (Logical) | 물리 큐비트 (Physical) | 보조 큐비트 (Ancilla) | 매직 상태 큐비트 (Magic State) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 결함 허용 대규모 범용 양자 알고리즘 | 하드웨어 칩 상의 개별 물리 소자 | QEC 에러 신드롬 패리티 추출 | 결함 허용 $T$-게이트 비선형 연산 주입 |
| 핵심 특징 | 코드 거리로 조절 가능한 논리 오류율 | 구현별 게이트·측정·유휴 오류 | 안정자 신드롬 간접 측정 | 증류를 통해 오류를 낮춘 비클리포드 자원 |
| 한계 | 수천 배의 물리 자원 오버헤드 소모 | 단독으로는 수십 게이트 이상 연산 불가 | 주기적 측정/리셋 회로 복잡도 | 정제 과정에서 막대한 물리 큐비트 소모 |

#### 한줄 요약
- 네 층위는 같은 소자를 역할로 나눈 것이므로 하드웨어 카탈로그의 큐비트 수는 이 중 어느 것도 특정하지 못하며, 그 수치만으로는 성능을 판단할 수 없다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **쇼어 알고리즘**: 정수 소인수분해를 다항 시간에 수행하지만, 실제 필요한 물리 자원량은 회로 구성·물리 오류율·정정 부호 선택에 따라 자릿수 단위로 달라지는 양자 알고리즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 알고리즘의 물리 자원·시간 오버헤드 | 표면 코드와 대안 부호의 연결성·복호 난이도 비교 | 하드웨어 제약 안에서 논리 자원 비용 최소화 |
| 매직 상태 정제의 공간·시간 비용 과다 | 알고리즘의 해당 게이트 수·깊이와 팩토리 처리량 공동 최적화 | 데이터 패치 유휴와 자원 대기 감소 |
| 물리 큐비트 간 간섭으로 상관 오류 발생 | 펄스 성형과 무작위 컴파일로 잡음 구조 변환 | 정정 부호가 가정하는 잡음 모델에 근접 |
| 멀리 떨어진 논리 큐비트 간 연산 지연 누적 | 칩 간 얽힘을 직접 만드는 모듈형 인터커넥트 도입 | 장거리 논리 연산의 중간 단계 축소 |

#### 한줄 요약
- 네 대책 모두 큐비트를 더 만드는 것이 아니라 필요한 수를 줄이는 방향이며, 자원 요구가 수천 배인 영역에서는 절감이 증설보다 훨씬 값싸다.

## Ⅶ. 결론

- 장기 결함 허용 계산은 물리 큐비트 수가 아니라 논리 큐비트 수·논리 오류율·논리 연산 속도로 평가하고, 오류 정정 없이 돌리는 단기 실험은 회로 깊이와 오류 완화 비용을 기준으로 평가 축을 분리
- 자원 추정이 널리 인용되는 **쇼어 알고리즘** 같은 사례도 부호와 오류율 가정에 따라 결과가 크게 달라지므로 전제를 함께 확인

#### 한줄 요약
- **결함 허용 양자 컴퓨팅(FTQC)** 관문은 큐비트를 몇 개 만드느냐가 아니라 물리 오류율을 임계치 아래로 내리는 일이며, 그 전까지 증설은 오류를 함께 늘릴 뿐이다.
