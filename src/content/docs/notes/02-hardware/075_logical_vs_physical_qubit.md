## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **물리 큐비트(Physical Qubit)**: 칩에 진짜로 박혀있는 하드웨어 알맹이로, 스치기만 해도 양자 파동이 깨져서 에러를 뱉어내는 끔찍한 개복치 체력이다.
- **논리 큐비트(Logical Qubit)**: 개복치 같은 물리 큐비트 수백 개를 방패막이로 갈아 넣어서, 에러가 전혀 나지 않도록 깎아 만든 절대 무적의 가상 계산 단위이다.
- **양자 오류 정정(Quantum Error Correction, QEC)**: 큐비트가 에러로 뻗기 전에, 여러 개의 큐비트를 묶어서 훔쳐보고 에러를 실시간으로 꿰매버리는 궁극의 연명 기술이다.

</details>

- 정의: 잡음이 있는 수십~수백 개의 **물리 큐비트**에 **양자 오류 정정**을 부호화해 에러가 전혀 없는 절대 무적의 계산 단위를 뽑아낸 **논리 큐비트**
- 배경: 에러가 밥 먹듯이 터지는 물리 큐비트만으로 1만 년짜리 긴 알고리즘을 돌리면, 계산 도중에 양자 파동이 박살 나서 **깊은 양자 회로의 성공 확률이 0에 수렴하기 때문**

#### 한줄 요약

- 진짜 칩에 박힌 약골 부품(물리 큐비트) 수백 개를 희생시켜서, 에러 없는 완벽한 가짜 부품 1개(논리 큐비트)를 연성해 내는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **코드 거리(Code Distance, d)**: 논리 큐비트를 지키는 바둑판 방패의 두께로, 거리를 키울수록 에러를 씹어먹는 맷집이 기하급수적으로 세진다.
- **파울리 프레임(Pauli Frame)**: 에러가 터졌을 때 큐비트를 건드려 고치지 않고, 소프트웨어 장부에 "얘 에러 났음" 하고 적어뒀다가 나중에 계산할 때 알아서 퉁치는 쿨한 회계 시스템이다.

</details>

- 칩 성능이 임계값 아래라는 전제하에, 바둑판 크기(**코드 거리**)를 미친 듯이 늘릴수록 논리 큐비트의 오류율이 기하급수적으로 소멸함.
- 단, **코드 거리**가 늘어날수록 하나의 논리 큐비트를 유지하기 위해 갈아 넣어야 하는 물리 큐비트 개수(면적)와 측정 자원 오버헤드가 살인적으로 폭발함.
- 명탐정(고전 복호기)과 결합해 에러를 쑤셔서 물리적으로 고치지 않고, 소프트웨어 장부에만 "얘 에러 났음" 하고 퉁치는 **파울리 프레임** 구조를 수용함.

#### 한줄 요약

- 바둑판(코드 거리)을 넓힐수록 맷집은 미친 듯이 세지지만, 그만큼 희생해야 할 물리 큐비트 개수도 살인적으로 늘어난다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **데이터 큐비트(Data Qubit)**: 1개의 논리 큐비트를 만들기 위해, 널찍한 표면 코드 바둑판 위에서 진짜 양자 정보를 쪼개서 품고 있는 십자가를 짊어진 생존자들이다.
- **앤실라 큐비트(Ancilla Qubit)**: 생존자들 사이에 껴서 "너 에러 났냐?" 하고 상태만 몰래 훔쳐보고 나오는 끄나풀 큐비트이다.
- **고전 복호기(Classical Decoder)**: 끄나풀들이 던져준 에러 지도를 보고, 가장 확률이 높은 에러 발생 경로를 찾아내는 일반 컴퓨터 명탐정 알고리즘이다.
- **최소 가중치 완전 매칭(Minimum-Weight Perfect Matching, MWPM)**: 명탐정이 점박이 에러 지도를 보고 가장 짧은 선으로 에러들을 이어버려서 진짜 범인을 지목하는 수학 수사 기법이다.

</details>

```text
[ 무적 논리 큐비트 제련 및 에러 감시 방어선 프레임워크 ]
                        [ 무적 논리 큐비트 ]
                                │
[ 데이터 큐비트 (생존자) ] ── [ 앤실라 큐비트 (끄나풀) ]
                                │
                      [ 고전 복호기 (명탐정) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **데이터 큐비트** | 1개의 논리 큐비트를 지탱하기 위해 표면 코드 격자판에 넓게 깔려 희생하는 수백 개의 하드웨어 큐비트 부품 |
| **보조(앤실라) 큐비트** | 데이터 큐비트들 사이에서 "에러 났냐?" 하고 X/Z 패리티만 몰래 훔쳐보고 나오는 끄나풀 큐비트 |
| **고전 복호기** | 끄나풀들이 던져준 에러 지도를 보고, 가장 확률이 높은 에러 경로를 찾아내는 명탐정 알고리즘 |
| 논리 큐비트 | 끄나풀과 명탐정의 피눈물 나는 서포트를 받아 완성된, 개발자가 믿고 쓰는 단 1개의 절대 무적 양자 계산 단위 |

#### 한줄 요약

- 수백 개의 데이터 큐비트와 끄나풀, 그리고 명탐정 컴퓨터가 영혼을 갈아 넣어 1개의 완벽한 논리 큐비트를 떠받든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **내결함 일정(Fault-Tolerant Schedule)**: 에러 하나가 터졌을 때 주변 놈들까지 다 같이 폭사하지 않도록, 순서를 기가 막히게 꼬아서 막아내는 방어 전술 맵핑이다.
- **실패 예산(Failure Budget)**: "1만 년짜리 계산 돌리는 동안 딱 1번의 삑사리까지만 봐줄게"라고 정해놓는, 알고리즘 전체를 관통하는 빡센 에러 허용 견적이다.

</details>

```text
[ 무적 논리 큐비트 제련 및 내결함 양자 십자포화 연산 흐름 ]
                               │
                               ▼
  [ 1. 실패 견적 및 맷집 산정: 실패 예산을 짜고 필요한 바둑판 크기(코드 거리)를 도출함 ]
                               │
                               ▼
  [ 2. 방어 전술 맵핑: 에러가 안 번지게 막아내는 내결함 일정을 짜서 펄스로 쪼개 번역함 ]
                               │
            ┌──────────────────┴──────────────────┐
            │        ( 연산 및 방어 반복 )        │
            │                  ▼                  │
            │ [ 3. 펄스 난사: 물리 게이트 인가 ]  │
            │                  │                  │
            │                  ▼                  │
            │ [ 4. 끄나풀 감시: 안정자 에러 수집] │
            │                  │                  │
            │                  ▼                  │
            │ [ 5. 명탐정 장부 갱신(복호/프레임)] │
            └──────────────────┬──────────────────┘
                               ▼
                    [ 에러 제로 논리 연산 결과 ]
```

### 동작 원리

1. 실패 견적 및 맷집 산정: 알고리즘 전체를 통틀어 딱 한 번의 삑사리만 허용하는 **실패 예산**을 짜고 필요한 바둑판 크기(**코드 거리**)를 도출함.
2. 내결함 스케줄링 맵핑: 오류가 나도 옆으로 안 번지게 막아내는 **내결함 일정**을 짜서 기계가 알아듣는 물리 게이트 펄스로 쪼개어 번역함.
3. 물리 펄스 난사 및 감시: **데이터 및 보조 큐비트** 군단에 게이트를 쏘고, 동시에 끄나풀을 돌려 에러가 터지는지 미친 듯이 감시함.
4. 명탐정 추리 및 장부 갱신: 에러가 나오면 즉시 **고전 복호기**가 범인을 찾고, 양자를 물리적으로 안 건드리고 **파울리 프레임** 장부만 슥 갱신함.

#### 한줄 요약

- 필요한 방패 두께(코드 거리)를 계산하고 방어 진형(내결함)을 짠 뒤, 계속 에러를 훔쳐보며 장부에 기록해 완벽한 계산을 끝마친다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **큐이씨 임계값(QEC Threshold)**: 하드웨어 에러율이 너무 높아서 방패(오류 정정)를 달아도 다 뚫려버리는 끔찍한 성능 커트라인이다. 칩이 이 커트라인보다 좋아야만 방패가 제값을 한다.

</details>

| 비교 항목 | **물리 큐비트** (Physical Qubit) | **논리 큐비트** (Logical Qubit) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 기계를 방금 사서 조율하거나, 에러 정정 포기하고 짧은 계산만 맛보기로 돌릴 시 | 세상의 모든 암호를 뚫어버리는 1만 년짜리 거대 알고리즘을 에러 한 방울 없이 내결함성(FTQC)으로 완주할 시 |
| 아키텍처 핵심 구현 특징 | 기판에 땜질 되어있는 눈에 보이는 진짜 하드웨어 칩 부품 알갱이 1개 그 자체 | 물리 큐비트 수천 개와 명탐정(복호기)의 똥꼬쇼가 결합되어 탄생한 눈에 보이지 않는 1개의 가상 무적 큐비트 |
| 극복해야 할 태생적 한계점 | 칩 크기를 키우고 큐비트 개수만 늘리면 뭐함, 에러가 미쳐 날뛰면 그냥 비싼 전기 먹는 하마일 뿐 | 100논리 큐비트짜리 컴퓨터를 만들려면 물리 큐비트 수십만 개를 희생시켜야 하는 살인적인 자원 오버헤드 장벽 |

#### 한줄 요약

- 물리 큐비트는 칩에 박혀있는 '에러 투성이 부품'이고, 논리 큐비트는 그걸 수백 개 갈아 넣어 만든 '완벽한 가상 부품'이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **매직 상태 정제(Magic-State Distillation)**: 논리 큐비트한테 삐딱한 고급 연산(T-Gate)을 먹이려면 큐비트 수만 개가 증발하니까, 전용 공장에서 완벽한 마법 가루(상태)를 깎아내서 주입하는 신박한 기법이다.
- **격자 수술(Lattice Surgery)**: 바둑판이 2D 평면이라 저 멀리 있는 큐비트랑 선을 잇기 빡세니까, 바둑판 구역(패치)을 수술하듯 잘랐다 붙였다 하면서 우아하게 얽히게 만드는 수술 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 논리 큐비트한테 삐딱한 고급 연산(T-Gate)을 먹이려면 수십 배의 물리 큐비트가 무식하게 증발해버리는 참사 | 공장 한쪽에 **매직 상태 정제** 전용 공장을 따로 지어 고품질 양자 상태(마법 가루)를 깎아낸 뒤 본진에 주입시킴 | 무식하게 큐비트를 낭비하지 않고도 복잡한 논리 연산을 깔끔하고 완벽하게(내결함성 보장) 해치움 |
| 바둑판(2D 표면 코드) 모양이라 저 멀리 있는 논리 큐비트랑 얽히게 만들려면 선을 이을 방법이 없어서 뻗어버림 | 논리 큐비트 패치(구역)들을 수술하듯 잘랐다 붙였다 하는 **격자 수술**(Lattice Surgery) 기법 전격 도입 | 멀리 있는 놈팽이들과 얽힐 때 물리적인 자리 이동(SWAP 낭비) 없이 평면 상에서 우아하게 연결 완료 |
| 칩 자체가 너무 썩어서 물리 에러율이 임계값을 넘어버리면, 바둑판(코드 거리)을 키울수록 에러가 더 폭발해버리는 자폭 사태 | 하드웨어를 뼈 깎듯 갈고닦아 어떻게든 물리 오류를 임계값 아래로 멱살 잡고 내린 뒤에야 **QEC** 적용 허가 | 임계값만 넘어서면 물리 큐비트를 들이부을 때마다 논리 에러가 0에 수렴해버리는 궁극의 방패 완성 |

#### 한줄 요약

- 복잡한 연산은 마법 공장(정제)으로 해결하고, 멀리 있는 놈팽이들은 바둑판을 찢고 붙이는(격자 수술) 방법으로 이어버려라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **물리 자원 산정(Physical Resource Estimation)**: "1만 년짜리 완벽한 계산을 하려면, 도대체 물리 큐비트 몇십만 개랑 냉장고 몇 대가 필요하냐?" 하고 견적서를 뽑는 과정이다.

</details>

- **물리 자원 산정** 원칙에 따라, 내결함 장시간 계산은 **논리 큐비트**, 장치 보정 및 얕은 실험은 **물리 큐비트**로 계층을 철저히 분리 적용함

#### 한줄 요약

- 진짜 거대 암호를 풀려면 살인적인 큐비트 물량으로 논리 큐비트를 만들고, 간단한 장난감 실험은 쌩 물리 큐비트로 돌려라.
