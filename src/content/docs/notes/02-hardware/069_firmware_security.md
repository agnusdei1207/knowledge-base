## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어(Firmware)**: 하드웨어 칩(ROM/Flash)에 상주하며 프로세서 초기화, 시스템 부팅 및 기기 제어를 담당하는 최하위 시스템 소프트웨어.
- **펌웨어 취약점(Firmware Vulnerability)**: 부트 롬, UEFI, BMC, 무선 모뎀 등의 코드 결함을 악용하여 하드웨어 제어권을 탈취하는 보안 결함.
- **Persistence(침해 지속성)**: OS 재설치나 스토리지 포맷 후에도 칩셋 비휘발성 메모리에 악성코드가 은닉 상주하여 시스템을 영구 장악하는 특성.

</details>

- 정의/개념: OS 부팅 이전(Pre-OS) 단계에서 실행되는 시스템 펌웨어(UEFI, BMC, MCU 등)의 취약점을 악용하여 OS 보안 통제를 무력화하고 영속적 은닉 권한을 획득하는 보안 위협 및 방어 체계
- 배경/필요성: OS 재설치 및 스토리지 포맷 후에도 악성코드가 잔존(Persistence)하는 **하드웨어 기반 루트킷/스파이웨어 위협 증가 및 공급망(Supply Chain) 단계의 펌웨어 무결성 보장 필수**

#### 한줄 요약

- OS 이전(Pre-OS) 단계 취약점 악용 방어 및 **펌웨어 무결성·지속성(Persistence) 차단 체계**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Pre-OS Execution**: OS 커널 및 백신(EDR) 소프트웨어가 로드되기 전에 먼저 실행되어 무소불위의 최고 권한(Ring -1/-2)을 장악하는 특성.
- **Supply Chain Attack(공급망 공격)**: 칩 제조, ODM 조립, 펌웨어 벤더(IBV) 배포 등 제조·유통 단계에서 악성 백도어가 삽입되는 위협.
- **BYOVD(Bring Your Own Vulnerable Driver)**: 유효한 정식 서명이 되어 있으나 취약점이 존재하는 구버전 드라이버/펌웨어를 악용해 보안을 우회하는 공격.

</details>

- OS 보안 통제와 백신 소프트웨어 감시를 우회하는 **Pre-OS 최고 권한 상주성**
- 칩 제조사, 부품 협력사, SI 조립 등 다단계 유통 과정에 걸친 **공급망 위협(Supply Chain Threat)** 노출
- 유효한 정식 제조사 서명을 보유한 구버전의 결함을 악용하는 **서명된 취약 펌웨어 다운그레이드 공격** 취약

#### 한줄 요약

- **Pre-OS 최고 권한 상주·공급망(Supply Chain) 위협 노출·서명된 취약 펌웨어 악용(BYOVD)**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SBOM(Software Bill of Materials)**: 펌웨어 내부에 포함된 오픈소스, 서드파티 라이브러리 및 드라이버의 버전과 출처를 기록한 소프트웨어 자재 명세서.
- **Platform Firmware Resiliency(PFR)**: NIST SP 800-193 표준으로 플랫폼 펌웨어의 보호(Protect), 탐지(Detect), 복구(Recover)를 하드웨어 기반으로 보장하는 메커니즘.

</details>

```text
[ 플랫폼 펌웨어 보안 및 회복 탄력성(PFR) 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 자산/SBOM 배포 관리 : 펌웨어 형상 및 CVE 공급망 추적     │
└──────────────────────────────┬──────────────────────────────┘
                               │ (OTA 업데이트 패키지)
┌──────────────────────────────┴──────────────────────────────┐
│ 2. 업데이트 검증 엔진 : 서명 검증 + eFuse 안티 롤백 검사    │
└──────┬───────────────────────┼───────────────────────┬──────┘
       │                       │                       │
┌──────▼──────┐         ┌──────▼──────┐         ┌──────▼──────┐
│ 3. 신뢰 저장소│        │ 4. A/B 플래시│        │ 5. 부트 복구│
│ (eFuse RoT, │         │ (Active /   │         │ (Health 감시│
│  서명 키 해시)│        │  Inactive)  │         │  자동 롤백) │
└─────────────┘         └─────────────┘         └─────────────┘
```

선의 의미: 자산/SBOM 배포 관리, 펌웨어 서명/버전 검증 엔진, eFuse 신뢰 저장소, A/B 듀얼 뱅크 플래시 및 부트 헬스체크 복구 제어기 간의 펌웨어 보안 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 자산 배포 관리 | 지금 기계에 깔린 펌웨어가 어느 회사 건지 족보(SBOM)를 추적하고 패치 주기를 멱살 잡고 통제하는 사령탑 |
| 업데이트 검증 | 다운받은 펌웨어의 도장(서명)이 찐인지 까보고, 롤백 꼼수를 부리는지 버전까지 뼛속 깊이 판정하는 검문소 |
| 신뢰 저장소 | 해커가 건드리지 못하게 칩 안에 박힌 퓨즈(eFuse)에 진짜 서명 키와 보안 카운터를 영원히 묻어두는 철통 금고 |
| 에이비 슬롯 | 업데이트 꼬여서 벽돌 되는 걸 막기 위해 방을 두 개(A/B) 파놓고, 삑사리 나면 즉시 옛날 방으로 튀는(롤백) 생존 파티션 |
| 부트 복구 제어 | 부팅이 똑바로 되는지 헬스체크하고, 미쳐 날뛰면 얄짤없이 비상 복구 모드로 시스템을 끌고 감 |

#### 한줄 요약

- **자산/SBOM 배포 관리·서명/버전 검증 엔진·eFuse 신뢰 저장소·A/B 듀얼 슬롯·부트 헬스 복구 제어**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Boot-Health Watchdog**: 새 펌웨어로 부팅 후 지정된 시간 내에 OS가 정상 헬스 신호를 보내지 않으면 이전 정상 슬롯으로 강제 복구하는 하드웨어 타이머.

</details>

```text
[ 펌웨어 안전 업데이트 및 롤백 복구 시퀀스 ]
                         │
                         ▼
   [ 1. 갱신 패키지의 SBOM 및 디바이스 타깃 호환성 검증 ]
                         │
                         ▼
   [ 2. eFuse RoT 기반 디지털 서명 및 안티 롤백 버전 검증 ]
                         │
                         ▼
   [ 3. 비활성 플래시 슬롯(Inactive Slot)에 새 펌웨어 바이너리 기록 ]
                         │
                         ▼
   [ 4. 새 슬롯으로 임시 부팅 시도 및 Boot-Health 감시 타이머 가동 ]
        /                                               \
   [ 정상 부팅 확인 (Health OK) ]                   [ 부팅 실패 또는 타임아웃 ]
        │                                               │
   [ 5. 새 슬롯을 Active 로 확정 ]                [ 이전 정상 슬롯으로 즉시 롤백 ]
```

**동작 원리**

1. **자산 검증**: 배포된 펌웨어 패키지의 SBOM 명세를 분석하여 대상 하드웨어와의 적합성 검증
2. **서명 및 롤백 검사**: 칩 다이 eFuse에 저장된 신뢰 키로 서명을 검증하고 다운그레이드 여부 판정
3. **비활성 슬롯 라이팅**: 현재 동작 중인 슬롯을 건드리지 않고 유휴 파티션에 안전하게 플래싱
4. **후보 부팅 검증**: 새 펌웨어로 부팅을 시도하며 하드웨어 헬스체크 타이머 가동
5. **확정 또는 롤백**: 정상 동작 확인 시 활성 파티션을 교체하고, 오류 발생 시 즉시 이전 버전으로 자동 복귀

#### 한줄 요약

- SBOM 족보 검증 $\to$ **eFuse 서명/안티 롤백 검증 $\to$ 비활성 슬롯 기록 $\to$ 후보 부팅 헬스체크 $\to$ 정상 시 슬롯 확정 / 이상 시 즉각 롤백**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Firmware vs Application Vulnerability**:
  - Firmware 취약점: Pre-OS/BMC 레벨, OS 포맷 후에도 침해 잔존, 백신 탐지 불가
  - App 취약점: User Space 레벨, 프로세스 종료/재설치로 제거 가능, EDR/백신 탐지

</details>

| 비교 항목 | 펌웨어 레벨 취약점 (Pre-OS / BMC / UEFI) | 운영체제/애플리케이션 취약점 (Post-Boot / App) |
|:---|:---|:---|
| 실행 권한 및 위치 | Ring -1(Hypervisor), Ring -2(SMM), Out-of-Band(BMC) | Ring 0(OS Kernel), Ring 3(User App Space) |
| 침해 잔존성 (Persistence) | OS 재설치 및 스토리지 포맷 후에도 칩셋에 영구 잔존 | OS 포맷, 디스크 초기화, 앱 삭제로 제거 가능 |
| 탐지 및 대응 방안 | OS 백신 탐지 불가, NIST SP 800-193 PFR/Secure Boot | EDR, 백신, WAF, OS 커널 패치 및 취약점 스캐너 |

#### 한줄 요약

- Pre-OS 은닉 영속 위협은 **펌웨어 취약점**, 포맷으로 제거 가능한 것은 **앱/OS 취약점**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OOB(Out-of-Band) Management Isolation**: 서버 관리용 BMC 네트워크를 서비스 트래픽과 물리적으로 분리된 전용 관리망(Dedicated VLAN/Physical LAN)으로 격리하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 꺼져있어도 해커가 관리 칩(**비엠씨**)을 뚫고 들어와서 펌웨어를 통째로 악성 코드로 덮어씌우는 끔찍한 대형 참사 | 일반 서비스 랜선이랑 관리용 랜선을 아예 물리적으로 찢어발겨 끊어버리는 얄짤없는 **관리망 격리** 적용 | 원격으로 최고 권한 칩셋을 후벼파는 네트워크 기반 펌웨어 위장 침투를 100% 원천 차단 보장 |
| 기판에 튀어나온 물리적인 핀에 해킹 장비를 꽂아 펌웨어를 통째로 복사해가는 무자비한 하드웨어 덤프 공격 발발 | 공장에서 출하할 때 **제이태그/유아트**(JTAG/UART) 구멍을 전자 퓨즈로 지져버리거나 암호로 뼛속까지 잠금 | 기판을 뜯고 칩을 뼛속까지 박살 내지 않는 한 펌웨어 코드를 밖으로 빼갈 수 없는 하드웨어 방어 달성 |
| 회사 직원이 서명 키를 통째로 유출해서 해커가 악성 펌웨어에 당당하게 진짜 도장을 찍고 침투하는 파국적 위험 | 키가 털렸을 때 바로 옛날 키를 박살 내고 새 키로 갈아타는 예비 키 준비 및 가차 없는 **키 폐기** 절차 장전 | 털린 키로 도장 찍힌 악성 펌웨어의 시스템 진입 승인을 칼같이 쳐내고 무력화시킴 |

#### 한줄 요약

- **OOB 관리망(BMC) 물리적 분리 격리·JTAG/UART 하드웨어 디버그 포트 잠금·eFuse 키 폐기(Revocation)**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PFR(Platform Firmware Resiliency) 3대 원칙**:
  - Protection: 비인가 펌웨어 플래싱 원천 차단
  - Detection: 부팅 시 변조된 펌웨어 감지
  - Recovery: 손상 감지 시 골든 이미지로 자동 자가 치유

</details>

- 차세대 보안 플랫폼 구축 시 **NIST SP 800-193 PFR(Platform Firmware Resiliency) 표준 준수 및 SBOM 기반 무결성 추적 체계 구축**

#### 한줄 요약

- **보호(Protection)·탐지(Detection)·복구(Recovery)**의 3대 PFR 원칙을 통한 펌웨어 회복 탄력성 확립
