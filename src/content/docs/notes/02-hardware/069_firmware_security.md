## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어 보안(Firmware Security)**: 메인보드 UEFI/BIOS, 서버 관리 컨트롤러(BMC), 네트워크 카드 등 시스템 하드웨어 최하단에서 동작하는 불휘발성 펌웨어의 무결성, 기밀성 및 가용성을 보호하는 보안 체계.
- **플랫폼 펌웨어 복원력(Platform Firmware Resiliency, PFR)**: 미국 국립표준기술원(NIST SP 800-193)에서 제정한 지침으로, 펌웨어 침해 시 보호(Protect), 탐지(Detect), 복구(Recover)를 하드웨어 수준에서 자동 수행하는 체계.

</details>

- 정의/개념: 하드웨어와 OS 사이의 시스템 펌웨어 변조를 방지하고 침해 시 정상 롤백 복원하는 **NIST SP 800-193 PFR 아키텍처**
- 배경/필요성: OS 하부 최고 특권 계층(Ring -2 SMM, BMC)을 겨냥한 **영구 지속형 펌웨어 루트킷 및 공급망 공격 위험 방어 한계**

#### 한줄 요약
- 펌웨어 침해에 대비해 PFR RoT 기반 보호·탐지·복구 체계를 구축한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NIST SP 800-193 3대 원칙**: 보호(Protect: 불법 쓰기 차단), 탐지(Detect: 부팅 전 서명 무결성 검증), 복구(Recover: 침해 감지 시 골든 이미지 자동 롤백).
- **소프트웨어 자재명세서(Software Bill of Materials, SBOM)**: 펌웨어 내부에 포함된 모든 오픈소스 및 서드파티 라이브러리의 버전과 구성 목록을 명시하여 공급망 취약점을 관리하는 명세서.
- **PFR RoT(Platform Root of Trust)**: 메인보드 상에서 메인 CPU보다 먼저 전원을 켜고 SPI 플래시 메모리 신호선을 하드웨어적으로 중계/필터링하는 전용 보안 프로세서(CPLD/FPGA).

</details>

- 독립 하드웨어 격리 감시: 메인 CPU와 물리적으로 분리된 **PFR RoT(보안 CPLD)**가 SPI 플래시 버스 직접 감시
- 3단계 자동 복원력 구현: 부팅 전 전자서명 검증(탐지), SPI 버스 불법 쓰기 차단(보호), 침해 시 백업 플래시 골든 이미지 자동 롤백(복구)
- 공급망 투명성 확보: **SBOM**을 통해 펌웨어 내부 서드파티 취약점(CVE) 조기 식별 및 패치

#### 한줄 요약
- PFR 보안 칩이 SPI 플래시 버스를 통제하여 불법 쓰기를 막고, 부팅 전 서명을 검증하며, 침해 시 골든 이미지로 자동 복원한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **골든 이미지(Golden Image)**: 읽기 전용으로 물리 보호되어 펌웨어 변조나 부팅 실패 시 즉각 복구에 사용되는 인증된 기준 펌웨어 바이너리.

</details>

```text
[PFR 펌웨어 복원력 아키텍처]
  │
  ├─ [보안 통제 칩셋] (독립 하드웨어 RoT)
  │     ├─ [PFR RoT (CPLD/FPGA)] (SPI 신호 가로채기 및 필터링)
  │     ├─ [보호/탐지 엔진] (서명 검증 및 불법 쓰기 차단)
  │     └─ [복구 엔진] (침해 감지 시 골든 이미지 롤백)
  │
  ├─ [스토리지 미디어 계층] (플래시 이중화)
  │     ├─ [활성 SPI 플래시] (UEFI/BMC 런타임 펌웨어)
  │     └─ [복구 SPI 플래시] (물리 쓰기 방지 골든 이미지)
  │
  └─ [서버 서브시스템 계층] (보호 대상)
        ├─ [호스트 CPU] (리셋 홀드 해제 후 부팅)
        └─ [BMC 컨트롤러] (독립 OOB 원격 관리 시스템)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| PFR RoT 칩 | SPI 플래시 검증과 복구 통제 |
| 활성 SPI 플래시 | CPU와 BMC의 실행 펌웨어 저장 |
| 복구 SPI 플래시 | 쓰기 보호된 **골든 이미지** 보관 |
| BMC 컨트롤러 | 서버 전원·냉각·원격 관리 수행 |
| SBOM 관리 시스템 | 펌웨어 구성요소와 CVE 추적 |

#### 한줄 요약
- PFR RoT 칩이 SPI 버스 앞단에 끼어들어 CPU와 BMC가 자기 펌웨어를 스스로 검증하던 자기참조 구조를 대신하므로 검증 주체가 검증 대상 바깥에 놓이고, 쓰기 금지된 복구 플래시가 침해 시의 수작업 재설치를 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SMM(System Management Mode)**: x86 CPU에서 OS 커널(Ring 0)보다 높은 권한으로 하드웨어 제어를 수행하는 Ring -2 최고 특권 실행 모드.
- **SPI 필터링(SPI Filtering)**: CPLD 기반 PFR 칩이 SPI 플래시 버스 신호를 가로채 인가되지 않은 쓰기 및 삭제 명령어를 하드웨어적으로 드롭(Drop)시키는 기술.

</details>

```text
[서버 전원 인가 및 PFR RoT 보안 칩 선제 기동]
                     │
                     ▼
1. 호스트 CPU 리셋 홀드(Reset Hold) 유지 및 활성 SPI 플래시 버스 차단
                     │
                     ▼
2. 활성 펌웨어 바이너리의 SHA-256 해시 및 전자서명 무결성 검증
    ┌────────────────┴────────────────┐
 [ 무결성 검증 실패 (변조/손상 감지) ] [ 무결성 검증 성공 (서명 정상) ]
    │                                 │
    ▼                                 ▼
3. 복구 플래시의 골든 이미지를        3. 호스트 CPU 리셋 핀 해제
    활성 플래시로 강제 복사 롤백       │
    │                                 ▼
    ▼                            4. 정상 펌웨어 실행 및 OS 부팅 진입
보안 감사 로그에 침해 이벤트 기록
    │
    ▼
재기록 펌웨어 무결성 재검증 수행
    ┌──────────┴──────────┐
 [ 재검증 성공 ]       [ 재검증 실패 ]
    │                     │
    ▼                     ▼
(CPU 리셋 해제)        5. 영구 부팅 차단 및 OOB 원격 보안 경보 송출
```

- 분기 결과: 펌웨어 변조 감지 시 CPU 기동을 차단하고 골든 이미지로 자동 복원한 후 부팅을 재개함

**동작 원리**

1. 서버 전원 인가 시 PFR CPLD의 CPU 리셋 핀 로우(Low) 고정을 통한 임의 펌웨어 코드 실행 물리 차단
2. PFR RoT 칩 내 암호 가속기의 활성 SPI 플래시 전 영역 스캔 및 SHA-256 해시 연산 기반 전자서명 검증
3. 변조 탐지 시 PFR 복구 엔진의 하드웨어 쓰기 보호 보조 플래시 골든 이미지 활성 플래시 강제 덮어쓰기 복구
4. 롤백 완료 후 재검증을 통한 정상 확인 시 CPU 리셋 홀드 해제 및 호스트 UEFI/BIOS의 정품 부팅 시퀀스 개시
5. 복구 실패 시 시스템 전원 영구 차단 및 OOB 네트워크 채널을 통한 중앙 보안 관제 침해 경보 텔레메트리 송출

#### 한줄 요약
- 리셋 보류는 CPU 기동을 늦추는 대가로 변조된 펌웨어가 단 한 번도 실행되지 못하게 하며, 골든 이미지라는 사본을 별도 영역에 둔 덕분에 복구가 부팅 흐름 안에서 끝난다.

## Ⅴ. 종류 및 비교

| 대상 구분 | 펌웨어 보안 (UEFI / BMC) | OS 커널 보안 (Kernel / EDR) | 애플리케이션 보안 (App / WAF) |
|:---|:---|:---|:---|
| 적용 기준 | OS 하부 최하위 하드웨어 제어권 탈취 및 영구 지속형 루트킷 방어 시 | OS 런타임 악성 프로세스 및 메모리 권한 상승 공격 방어 시 | 외부 웹 공격 및 비인가 사용자 API 입력값 변조 위협 방어 시 |
| 핵심 특징 | Ring -2 SMM/Ring -3 BMC 최고 특권 영역 보호, NIST SP 800-193 PFR 하드웨어 RoT, SPI 플래시 버스 가드 및 골든 롤백 | Ring 0 커널 공간 감시, SELinux/ASLR/EDR 기반 동적 행위 통제, 메모리 무결성 감시 및 OS 레벨 치료 | Ring 3 사용자 공간 보호, WAF/입력값 검증/TLS 암호화 적용, 침입 탐지(IPS) 및 앱 프로세스 격리 |
| 한계 | 독립 보안 CPLD/FPGA 추가에 따른 하드웨어 BoM 단가 상승 및 부팅 시퀀스 지연 | 펌웨어 레벨 감염 시 커널 레벨 보안 모듈이 완전히 무력화되어 침해 감지 불가 | 상위 계층 보안에 국한되어 커널 및 펌웨어 레벨의 저수준 공격 방어 불가 |

#### 한줄 요약
- 펌웨어는 최고 특권 계층이므로 OS나 앱 보안 소프트웨어로는 감지할 수 없으며, 독립 하드웨어 PFR 기반으로만 방어할 수 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OOB(Out-of-Band) 관리망**: 업무용 데이터 트래픽과 완전히 분리되어 BMC 원격 제어 트래픽만 전담하는 독립 물리 네트워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인터넷에 노출된 관리 포트를 통한 BMC 원격 백도어 침투 | **OOB 관리망 물리적 분리** 및 mTLS 상호 인증 | 외부 인터넷을 통한 펌웨어 침투 경로 차단 |
| 서드파티 펌웨어 공급망을 통한 제로데이 취약점 유입 | **펌웨어 SBOM 자동 생성** 및 취약점 상시 스캐닝 | 공급망 취약점 신속 식별 및 패치 단축 |
| 물리적 SPI 플래시 롬 라이터기를 통한 악성 코드 주입 | **PFR 기반 SPI 버스 가드** 및 하드웨어 쓰기 방지 핀 고정 | 물리적 롬 조작 및 하드웨어 해킹 무력화 |

#### 한줄 요약
- 실무에서는 OOB 관리망 격리로 침투를 막고, SBOM으로 공급망을 관리하며, 하드웨어 버스 가드로 물리 해킹을 차단한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: 서버 메인보드의 독립 프로세서로, 본체 전원 상태와 무관하게 원격 전원 제어, 콘솔 리디렉션, 센서 모니터링을 전담하는 관리 칩.
- **제로 트러스트(Zero Trust)**: 내부 네트워크나 하드웨어라도 절대 신뢰하지 않고 모든 접근 요청에 대해 지속적인 인증과 최소 권한을 검증하는 보안 모델.

</details>

- 최하위 시스템 특권 계층 보호를 위해 NIST SP 800-193 플랫폼 펌웨어 복원력(PFR: Protect, Detect, Recover) 하드웨어 RoT 아키텍처 구축이 글로벌 인프라 보안 표준으로 정착.
- 향후 공급망 투명성을 위한 펌웨어 SBOM 의무화 및 OOB 관리망 제로 트러스트(Zero Trust) 통제 결합과 함께, 물리적 SPI 버스 필터링 및 자동 골든 롤백 체계의 전산실 인프라 선제 확립 필수.

#### 한줄 요약
- **펌웨어 보안**은 시스템 신뢰의 절대적 전제 조건이며, NIST SP 800-193 기반의 하드웨어 PFR 복원력 구축으로 완성된다.
