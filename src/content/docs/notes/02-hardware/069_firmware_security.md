## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어(Firmware)**: 하드웨어 초기화, 부팅, 전력 및 저수준 제어를 담당하는 불휘발성 메모리 내 소프트웨어(UEFI/BIOS, BMC 등).
- **플랫폼 펌웨어 복원력(PFR, Platform Firmware Resiliency)**: NIST SP 800-193 지침의 보호·탐지·복구 원칙으로 플랫폼 펌웨어를 방어하는 체계.

</details>

- 정의/개념: 하드웨어와 OS 사이의 **펌웨어** 변조를 막고 오염된 이미지를 자동 복원하는 **플랫폼 펌웨어 복원력(PFR)** 체계
- 배경/필요성: 기존 OS 중심 소프트웨어 보안 체계로는 **펌웨어 레벨 감염 시 상위 보안 통제 무력화 방지 불가**

#### 한줄 요약
- 펌웨어 레벨의 침해는 OS 기반 보안 소프트웨어를 완전히 무력화하므로, 하드웨어 RoT 기반의 보호·탐지·복구 체계가 필수적이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NIST SP 800-193 3대 원칙**: 보호(Protect, 불법 쓰기 차단), 탐지(Detect, 무결성 훼손 감지), 복구(Recover, 정상 이미지 자동 복원).
- **SBOM(Software Bill of Materials)**: 펌웨어 내부에 포함된 오픈소스 및 서드파티 라이브러리의 버전과 구성 목록을 명시한 자재명세서.

</details>

- **NIST SP 800-193 3대 원칙**(보호·탐지·복구)을 각각 독립 하드웨어 경로로 설계
- **SBOM** 연계를 통해 펌웨어 내부 서드파티 컴포넌트의 공급망 취약점 신속 추적
- 메인 CPU와 물리적으로 분리된 전용 보안 프로세서(PFR RoT) 기반 상시 감시

#### 한줄 요약
- 불법 쓰기 방지(보호), 부팅 전 서명 검증(탐지), 골든 이미지 자동 롤백(복구)의 3단계 복원력을 구현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: 서버의 전원, 쿨링, 원격 KVM 콘솔을 독립적으로 제어하는 서버 관리 전용 보조 프로세서.
- **PFR RoT(Platform Root of Trust)**: 메인 CPU와 독립적으로 동작하며 SPI 플래시 메모리의 펌웨어를 상시 검증하는 전용 보안 하드웨어.

</details>

```text
[플랫폼 펌웨어 복원력(PFR) 아키텍처]
|-- PFR RoT (전용 보안 FPGA/CPLD 칩)
|   |-- 보호 엔진 (SPI 플래시 쓰기 차단 및 버스 가드)
|   |-- 탐지 엔진 (SHA-256 해시 및 전자서명 암호학적 검증)
|   `-- 복구 엔진 (골든 이미지 자동 롤백 하드웨어 제어)
|-- 활성 SPI 플래시 (현재 실행 중인 UEFI/BMC 펌웨어)
|-- 복구 SPI 플래시 (읽기 전용 골든 백업 이미지 보관)
`-- 감시 대상 서브시스템 (호스트 CPU UEFI/BIOS 및 원격 관리 BMC)
```

선의 의미: 계층 및 하드웨어 버스 가드 구조

| 구성요소 | 책임 |
|:---|:---|
| **PFR RoT** | 부팅 전 펌웨어 서명 검증, SPI 버스 필터링 및 침해 시 자동 복구 총괄 |
| 활성 SPI 플래시 | 호스트 CPU 및 BMC가 실시간 실행하는 주 펌웨어 바이너리 저장 |
| 복구 SPI 플래시 | 물리적으로 쓰기 금지된 무결한 **골든 이미지(Golden Image)** 영구 보관 |
| **BMC** | 서버 전원, 냉각, 원격 제어를 담당하는 고특권 관리 컨트롤러 |
| SBOM 관리자 | 펌웨어 내 취약 오픈소스 라이브러리 목록화 및 CVE 실시간 매핑 |

#### 한줄 요약
- PFR RoT 칩이 SPI 플래시 버스 앞단에 위치하여 CPU 부팅 전 펌웨어를 검증하고 침해 시 골든 이미지로 복구한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **골든 이미지(Golden Image)**: 복구에 사용할 서명·버전이 검증되고 별도 쓰기 정책으로 보호된 기준 펌웨어 이미지.

</details>

```text
전원 인가 → PFR RoT가 CPU 리셋을 붙잡아 부팅 보류
        │
   활성 플래시 펌웨어의 전자서명 및 해시가 유효한가?
   ┌────┴─────┐
  예           아니오 (변조 감지)
   │             │
   │        복구 플래시의 골든 이미지를 활성 영역에 강제 재기록
   │             │
   │        불휘발성 보안 로그에 침해 시각 및 상세 유형 기록
   │             │
   │        재기록된 펌웨어 이미지 2차 무결성 검증
   │        ┌────┴─────┐
   │      통과          실패
   │        │             │
   └────┬───┘        영구 부팅 차단 및 관리자 알림
        │
   CPU 리셋 해제 후 정상 부팅 시퀀스 개시
```

#### 한줄 요약
- 전원 인가 → 펌웨어 무결성 검증 → 변조 시 골든 이미지 복구 및 로그 기록 → CPU 리셋 해제 후 정상 부팅 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **UEFI/BIOS 보안**: 마더보드 최하위 부팅 펌웨어의 런타임 침해 및 SMM 루트킷을 방어하는 체계.
- **BMC 보안**: 아웃오브밴드 원격 관리 인터페이스를 통한 원격 침해 및 펌웨어 변조를 차단하는 체계.

</details>

| 보안 계층 영역 | 펌웨어 보안 (UEFI/BMC) | OS 커널 보안 | 애플리케이션 보안 | 물리 하드웨어 보안 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 최하위 시스템 신뢰 기반 구축 | 운영체제 런타임 메모리 보호 | 웹/DB 비즈니스 서비스 보호 | 칩 물리 해킹(사이드채널/프로빙) 방어 |
| 핵심 특징 | NIST SP 800-193 PFR 및 하드웨어 RoT | SELinux, ASLR, 커널 무결성 보호 | WAF, 입력값 검증, 암호화 통신 | PUF, 글리치 감지, 탬퍼 실링 |
| 한계 | 개발 주기 길고 칩 레벨 지원 필수 | 펌웨어 레벨 감염 시 전면 무력화 | 상위 레이어에만 국한(인프라 무방비) | 설계 단가 상승 및 양산 복잡도 |

#### 한줄 요약
- 펌웨어 보안은 OS와 앱 보안의 전제 조건이며, NIST SP 800-193 기반 PFR 구현이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **아웃오브밴드(OOB, Out-of-Band) 관리망**: 업무 데이터 트래픽과 물리적으로 분리되어 서버 관리(BMC) 트래픽만 전담하는 독립 전용 네트워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 관리 포트 노출로 인한 BMC 원격 루트킷 감염 | **OOB 관리망** 물리적 분리 및 상호 TLS(mTLS) 인증 | 업무망 경유 원격 침투 경로 원천 차단 |
| 서드파티 펌웨어 공급망 취약점(CVE) 유입 | 펌웨어 **SBOM** 자동 생성 및 취약점 상시 스캐닝 | 취약 라이브러리 신속 식별 및 패치 타임라인 단축 |
| 물리적 SPI 플래시 라이터기를 통한 악성 롬 라이팅 | PFR 기반 SPI 버스 가드 및 하드웨어 쓰기 방지(WP) 핀 고정 | 물리적 클립온(Clip-on) 롬 조작 무력화 |
| 펌웨어 업데이트 중 전원 상실로 인한 벽돌화 | 듀얼 SPI 플래시 및 부팅 성공 확인 기반 롤백 | 펌웨어 손상 시 무중단 자동 복원 보장 |

#### 한줄 요약
- OOB 관리망 격리, SBOM 기반 취약점 추적, 하드웨어 버스 가드 및 듀얼 플래시 롤백 체계로 플랫폼 펌웨어를 완벽히 방어한다.

## Ⅶ. 결론

- 서버 및 미션 크리티컬 기기는 **NIST SP 800-193 기반 PFR RoT**를 탑재하고, **SBOM 관리 및 OOB 격리**를 병행하여 하드웨어 공급망 보안 확립

#### 한줄 요약
- 펌웨어 보안은 부팅 전 탐지와 자동 복원 능력을 하드웨어 수준에서 갖추는 플랫폼 복원력(PFR) 중심의 설계가 필수적이다.
