## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어(Firmware)**: 윈도우(OS)가 뜨기 전부터 칩셋과 하드웨어를 깨우고 주무르기 위해 플래시 메모리에 박혀있는 가장 밑바닥의 지배자 소프트웨어이다.
- **펌웨어 취약점(Firmware Vulnerability)**: 펌웨어를 대충 짜서 생긴 구멍을 틈타 해커가 악성 코드를 쑤셔 넣어, 윈도우 백신이 뜨기도 전에 컴퓨터를 장악해버리는 끔찍한 사태이다.
- **침해 잔존성(Persistence)**: 컴퓨터를 포맷하고 하드디스크를 새것으로 갈아 끼워도, 메인보드 칩(펌웨어)에 악성 코드가 기생하며 영원히 살아남아 해킹을 이어가는 악랄한 생명력이다.

</details>

- 정의: 윈도우(OS)가 뜨기 전에 하드웨어를 주무르는 펌웨어의 결함을 악용해, OS 보안 도구로는 절대 못 잡는 초고권한 **침해 잔존성**을 확보하는 끔찍한 보안 위협
- 배경: 윈도우 백신만으로는 **부팅 이전 변조와 복구 영역 검증이 뼛속까지 불가능**하여, 하드웨어 밑단이 털리는 걸 막을 수 없기 때문

#### 한줄 요약

- 컴퓨터를 포맷해도 메인보드 칩에 살아남아 계속 해킹하는 징그러운 악성 코드를 막기 위해 펌웨어 단에서부터 문단속을 하는 보안 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **오에스 이전 실행(Pre-OS Execution)**: 윈도우 보안 시스템이나 백신이 켜지기도 전에 펌웨어가 먼저 켜져서 모든 시스템의 통제권을 무소불위로 휘두르는 특성이다.
- **공급망 위협(Supply Chain Threat)**: 대만 칩 공장, 중국 조립 공장, 배송 단계를 거치는 와중에 해커나 스파이가 중간에 펌웨어를 몰래 뜯어고쳐 악성 코드를 박아버리는 치명적 위협이다.
- **서명된 취약 코드(Signed Vulnerable Code)**: 해커가 만든 게 아니라 제조사가 만든 정식 펌웨어라서 진짜 도장(서명)이 찍혀있는데, 안에는 털리기 딱 좋은 보안 구멍이 숭숭 뚫려있는 환장할 코드이다.

</details>

- 백신이나 OS 보안 커널이 감히 건드릴 수 없는 **오에스 이전 실행**의 깡패 같은 최고 권한 상주를 즐김.
- 칩 공장, 대만 펌웨어 벤더, 제조사를 거치며 중간에 해커가 악성 코드를 쑤셔 넣는 **공급망 위협**에 찰지게 노출됨.
- 도장은 진짜(유효한 정식 서명)인데 코드 안에 구멍이 뚫려있어 보안 방어벽을 당당히 패스하는 **서명된 취약 코드** 악용 공격 패턴을 보임.

#### 한줄 요약

- 백신이 켜지기 전에 최고 권한을 잡고, 공장에서 올 때부터 악성 코드를 묻혀오거나 제조사 정품인데 보안에 빵꾸가 난 코드를 이용해 뚫는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자산 배포 관리(Asset/Deployment Management)**: 지금 폰이나 차에 깔린 펌웨어가 어느 회사 건지 족보(SBOM)를 추적하고 업데이트 주기를 멱살 잡고 통제하는 사령탑이다.
- **업데이트 검증(Update Verification)**: 다운받은 펌웨어의 도장(서명)이 찐인지 까보고, 롤백 꼼수를 부리는지 버전까지 뼛속 깊이 판정하는 보안 검문소이다.
- **신뢰 저장소(Trust Store)**: 해커가 건드리지 못하게 칩 안에 박힌 퓨즈(eFuse)에 진짜 서명 키와 보안 카운터를 영원히 묻어두는 철통 금고이다.
- **에이비 슬롯(A/B Slot)**: 펌웨어 업데이트가 꼬여서 기계가 쇳덩이(벽돌) 되는 걸 막기 위해 방을 두 개(A, B) 파놓고, 삑사리 나면 즉시 옛날 방으로 튀는(롤백) 생존 구조이다.

</details>

```text
[ 펌웨어 무선 업데이트 십자포화 검증 및 생존 롤백 프레임워크 ]
                        [ 자산 배포 관리 (사령탑) ]
                               │
[ 신뢰 저장소 (금고) ] ─── [ 업데이트 검증 (검문소) ] ─── [ 에이비 슬롯 (대피소) ]
                               │
                        [ 부트 복구 제어 (헬스체크) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **자산 배포 관리** | 지금 기계에 깔린 펌웨어가 어느 회사 건지 족보(SBOM)를 추적하고 패치 주기를 멱살 잡고 통제하는 사령탑 |
| **업데이트 검증** | 다운받은 펌웨어의 도장(서명)이 찐인지 까보고, 롤백 꼼수를 부리는지 버전까지 뼛속 깊이 판정하는 검문소 |
| **신뢰 저장소** | 해커가 건드리지 못하게 칩 안에 박힌 퓨즈(eFuse)에 진짜 서명 키와 보안 카운터를 영원히 묻어두는 철통 금고 |
| **에이비 슬롯** | 업데이트 꼬여서 벽돌 되는 걸 막기 위해 방을 두 개(A/B) 파놓고, 삑사리 나면 즉시 옛날 방으로 튀는(롤백) 생존 파티션 |
| 부트 복구 제어 | 부팅이 똑바로 되는지 헬스체크하고, 미쳐 날뛰면 얄짤없이 비상 복구 모드로 시스템을 끌고 감 |

#### 한줄 요약

- 사령탑이 업데이트를 뿌리면, 검문소가 찐인지 검사하고 잉여 슬롯(A/B)에 깔아본 뒤, 문제 생기면 부트 제어가 예전 상태로 도망간다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **갱신 패키지(Update Package)**: 제조사에서 내려준 업데이트 파일 덩어리로, 암호화된 도장과 새 펌웨어 코드가 하나로 묶인 압축 파일이다.
- **비활성 슬롯(Inactive Slot)**: A/B 두 방 중에서 지금 안 쓰고 놀고 있는 빈방으로, 새 업데이트 파일을 까는 임시 대피소 역할이다.
- **부팅 건강 감시(Boot-Health Monitoring)**: 업데이트 끝내고 재부팅했을 때 윈도우가 안 터지는지, 블루스크린 안 뜨는지 빡세게 지켜보는 의사이다.

</details>

```text
[ 펌웨어 무선 업데이트 십자포화 검증 및 생존 롤백 잔혹 흐름 ]
                               │
                               ▼
  [ 1. 족보 검증: 날아온 갱신 패키지가 우리 기계랑 딱 맞는지 SBOM 뼈와 살을 분리하며 체크 ]
                               │
                               ▼
 [ 2. 서명•버전 검증: 금고 키로 도장이 찐인지 까보고, 옛날 버전으로 꼼수 치는지 카운터 검증 ]
                               │
                               ▼
      [ 3. 빈방 입주: 검증을 통과한 패키지를 놀고 있는 잉여 방(비활성 슬롯)에 조심스레 깜 ]
                               │
                               ▼
    [ 4. 헬스 검증: 빈방으로 껐다 켜보면서 윈도우가 안 터지는지 부팅 건강 감시를 빡세게 돌림 ]
                               │
                  +------------+-------------+
                  |                          |
                (정상)                     (실패)
                  ▼                          ▼
 [ 5. 탕탕탕! 새 방을 활성으로 확정 ]   [ 뒤도 안 보고 원래 있던 방으로 즉시 롤백 빤스런 ]
```

### 동작 원리

1. 자산 의존성 검증: 날아온 **갱신 패키지**의 족보(SBOM)가 지금 기계랑 딱 맞는지 뼈와 살을 분리하며 체크함.
2. 서명 및 롤백 검증: 금고(**신뢰 저장소**)의 진짜 키로 서명을 까보고, 옛날 버전으로 꼼수 치는지 카운터를 무자비하게 털어봄.
3. 잉여 방에 기록: 검증을 통과한 패키지를 현재 돌아가고 있는 방 말고, 놀고 있는 빈방(**비활성 슬롯**)에 조심스레 깔아둠.
4. 후보 부팅 및 헬스 검증: 빈방으로 껐다 켜보면서 윈도우가 안 터지는지 **부팅 건강 감시**를 빡세게 돌림.
5. 확정 또는 빤스런: 부팅 성공하면 새 방을 확정하고, 뻑나면 뒤도 안 돌아보고 원래 있던 방으로 즉시 롤백함.

#### 한줄 요약

- 업데이트 파일의 족보와 도장을 깐깐히 검사하고 잉여 방에 깐 뒤, 재부팅해서 윈도우가 살면 확정, 블루스크린 뜨면 옛날 방으로 롤백한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **비엠씨(Baseboard Management Controller, BMC)**: 윈도우가 꺼져있든 말든 뒤에서 몰래 서버 전원을 켜고 끄며 하드웨어를 통제하는 무소불위의 원격 관리용 칩셋이다.
- **권한 상승(Privilege Escalation)**: 일반 찌끄레기 유저 권한으로 들어와서 OS의 빈틈을 파고들어 최고 권한자(루트) 행세를 하는 끔찍한 신분 세탁 해킹이다.

</details>

| 취약점 위치 | **펌웨어 취약점** (Firmware Level) | **애플리케이션 취약점** (App Level) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 컴퓨터가 꺼져있어도 원격으로 멱살 잡는 **비엠씨**(BMC) 및 메인보드 하드웨어 최하단 구역 | 윈도우 안에서 돌아가는 크롬, 카톡, 엑셀 같은 평범한 일반 유저 영역 앱 |
| 아키텍처 핵심 구현 특징 | 백신(OS) 따위가 감히 쳐다도 못 보는 **오에스 이전**(Pre-OS)의 신적인 최고 권한 제어 지배력 장악 | 윈도우 운영체제가 그어놓은 선 안에서만 놀아야 하는 철저히 제한된 찌끄레기 권한 환경 |
| 극복해야 할 태생적 한계점 | 포맷을 하고 하드를 통째로 갈아 끼워도 메인보드 칩에 기생하며 영원히 살아남는 악랄한 **침해 잔존성** | 앱이 털리면 해커가 **권한 상승** 꼼수를 써서 윈도우 커널까지 통째로 파먹어 들어가는 침해 연쇄 붕괴 |

#### 한줄 요약

- 앱이 털리면 윈도우 포맷하면 그만이지만, 펌웨어가 털리면 포맷하고 하드를 바꿔도 메인보드에 기생해서 평생 널 엿먹인다(침해 잔존성).

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **관리망 격리(Management-Network Isolation)**: 해커가 웹 서비스 파도타기로 관리용 BMC 칩에 접근 못 하게, 일반 랜선이랑 관리용 랜선을 아예 물리적으로 가위로 잘라 찢어놓는 철통 보안이다.
- **제이태그 유아트(JTAG/UART)**: 기판 개발할 때 쓰던 테스트용 구멍들인데, 공장 출하 시 이거 안 막으면 해커가 여기다 선 꽂고 펌웨어를 통째로 쪽쪽 빨아간다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 꺼져있어도 해커가 관리 칩(**비엠씨**)을 뚫고 들어와서 펌웨어를 통째로 악성 코드로 덮어씌우는 끔찍한 대형 참사 | 일반 서비스 랜선이랑 관리용 랜선을 아예 물리적으로 찢어발겨 끊어버리는 얄짤없는 **관리망 격리** 적용 | 원격으로 최고 권한 칩셋을 후벼파는 네트워크 기반 펌웨어 위장 침투를 100% 원천 차단 보장 |
| 기판에 튀어나온 물리적인 핀에 해킹 장비를 꽂아 펌웨어를 통째로 복사해가는 무자비한 하드웨어 덤프 공격 발발 | 공장에서 출하할 때 **제이태그/유아트**(JTAG/UART) 구멍을 전자 퓨즈로 지져버리거나 암호로 뼛속까지 잠금 | 기판을 뜯고 칩을 뼛속까지 박살 내지 않는 한 펌웨어 코드를 밖으로 빼갈 수 없는 하드웨어 방어 달성 |
| 회사 직원이 서명 키를 통째로 유출해서 해커가 악성 펌웨어에 당당하게 진짜 도장을 찍고 침투하는 파국적 위험 | 키가 털렸을 때 바로 옛날 키를 박살 내고 새 키로 갈아타는 예비 키 준비 및 가차 없는 **키 폐기** 절차 장전 | 털린 키로 도장 찍힌 악성 펌웨어의 시스템 진입 승인을 칼같이 쳐내고 무력화시킴 |

#### 한줄 요약

- 원격 관리 랜선은 물리적으로 찢어놓고(격리), 기판의 구멍(JTAG)은 출하 때 땜질해버리며, 키가 털리면 즉시 블랙리스트(키 폐기)에 올려라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **갱신 승인(Update Approval)**: "도장이 진짜냐?", "옛날 버전 꼼수냐?", "우리 기계가 맞냐(SBOM)?"라는 3단 콤보 검문을 완벽히 통과해야만 깔아주는 무자비한 허락 절차이다.

</details>

- **갱신 승인** 원칙에 따라 부팅 검증은 **Secure Boot·Anti-Rollback**으로, 업데이트 실패 복구는 **A/B 슬롯**, 파급 추적은 **SBOM**으로 방어 기조 확립함

#### 한줄 요약

- 켤 때는 보안 부팅, 깔 때는 A/B 슬롯, 털렸을 땐 족보(SBOM) 추적이라는 삼위일체로 펌웨어 뼛속까지 철통 방어해라.
