## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어(Firmware)**: 하드웨어 초기화, 부팅, 전력 및 저수준 제어를 담당하는 불휘발성 메모리 내 소프트웨어(UEFI/BIOS, BMC 등).
- **플랫폼 펌웨어 복원력(PFR, Platform Firmware Resiliency)**: NIST SP 800-193 지침의 보호·탐지·복구 원칙으로 플랫폼 펌웨어를 방어하는 체계.

</details>

- 정의/개념: 하드웨어와 OS 사이의 **펌웨어(Firmware)** 변조를 막고 오염된 이미지를 되돌리는 **플랫폼 펌웨어 복원력(PFR, Platform Firmware Resiliency)** 체계
- 배경/필요성: 펌웨어는 OS보다 먼저 실행되므로 여기서 감염되면 백신·EDR 등 상위 통제가 모두 무력해짐

#### 한줄 요약
- 상위 계층 보안이 아무리 촘촘해도 자신을 실행시켜 준 코드는 검증하지 못하므로, 신뢰는 결국 가장 먼저 실행되는 곳에서 만들어져야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NIST SP 800-193 3대 원칙**: 보호(Protect, 불법 쓰기 차단), 탐지(Detect, 무결성 훼손 감지), 복구(Recover, 정상 이미지 자동 복원).
- **SBOM(Software Bill of Materials)**: 펌웨어 내부에 포함된 오픈소스 및 서드파티 라이브러리의 버전과 구성 목록을 명시한 자재명세서.

</details>

- **NIST SP 800-193 3대 원칙**인 보호·탐지·복구를 각각 독립 경로로 설계
- **SBOM(Software Bill of Materials)** 연계로 펌웨어 내부 구성요소와 취약 버전 추적
- 메인 CPU와 분리된 전용 보안 칩이 독립 경로로 상시 감시

#### 한줄 요약
- 세 원칙 중 복구가 있다는 점이 이 체계를 다른 보안과 구분하며, 침해를 막지 못한 경우까지 설계 범위에 넣었다는 뜻이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: 서버의 전원, 쿨링, 원격 KVM 콘솔을 독립적으로 제어하는 서버 관리 전용 보조 프로세서.
- **PFR RoT(Platform Root of Trust)**: 메인 CPU와 독립적으로 동작하며 SPI 플래시 메모리의 펌웨어를 상시 검증하는 전용 보안 하드웨어.

</details>

```text
[플랫폼 펌웨어 복원력 구조]
├─ 독립 하드웨어 신뢰 뿌리 (전용 보안 칩)
│  ├─ 보호 엔진 (플래시 쓰기 잠금·버스 필터링)
│  ├─ 탐지 엔진 (해시·서명 검증)
│  └─ 복구 엔진 (백업 이미지 자동 복원)
├─ 활성 플래시 (현재 실행 중인 펌웨어)
├─ 복구 플래시 (읽기 전용 골든 이미지)
└─ 보호 대상
   ├─ 호스트 CPU 펌웨어
   └─ 관리 컨트롤러 펌웨어
```

선의 의미: 가지(`├─`)는 소유 관계이며, 보안 칩이 플래시와 CPU 사이에 끼어 있어 모든 접근이 이 지점을 지남

| 구성요소 | 책임 |
|:---|:---|
| **PFR RoT(Platform Root of Trust)** | 부팅 전 펌웨어 서명 검증과 플래시 버스 필터링 |
| 활성 플래시 | 현재 실행 중인 펌웨어 바이너리 저장 |
| 복구 플래시 | 복원 기준이 되는 읽기 전용 이미지 보관 |
| **BMC(Baseboard Management Controller)** | 전원·냉각·원격 콘솔을 독립 제어하는 관리 프로세서 |
| SBOM 관리자 | 펌웨어 내 취약 구성요소를 식별하고 추적 |

#### 한줄 요약
- 감시 주체가 감시 대상과 같은 CPU에서 돌지 않는다는 점이 핵심이며, 이 독립성이 없으면 침해된 시스템이 스스로 무결하다고 보고하게 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **골든 이미지(Golden Image)**: 복구에 사용할 서명·버전이 검증되고 별도 쓰기 정책으로 보호된 기준 펌웨어 이미지.

</details>

```text
전원 인가 → 보안 칩이 CPU 리셋을 붙잡아 부팅 보류
        │
   활성 플래시 펌웨어의 서명·해시가 유효한가?
   ┌────┴─────┐
  예           아니오 (변조 감지)
   │             │
   │        복구 플래시의 골든 이미지를 활성 영역에 재기록
   │             │
   │        불휘발성 로그에 침해 시각·유형 기록
   │             │
   │        재기록 이미지 재검증
   │        ┌────┴─────┐
   │      통과          실패
   │        │             │
   └────┬───┘        부팅 거부·알림
        │
   CPU 리셋 해제 후 정상 부팅
```

분기 결과: 복구 경로 끝에도 재검증이 붙어 있어 복구 이미지 자체가 오염된 경우까지 걸러지며, 복구 수단을 신뢰하지 않는 설계가 이 체계의 특징

#### 한줄 요약
- **골든 이미지(Golden Image)** 활용 쓰기 금지로 묶어 두는 이유가 여기서 드러나며, 복구 수단이 공격 대상이 되는 순간 이 흐름은 무한 재감염 고리로 바뀐다.

## Ⅴ. 종류 및 비교

| 보안 계층 영역 | 펌웨어 보안 (UEFI/BMC) | OS 커널 보안 | 애플리케이션 보안 | 물리 하드웨어 보안 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 최하위 시스템 신뢰 기반 구축 | 운영체제 런타임 메모리 보호 | 웹/DB 비즈니스 서비스 보호 | 칩 물리 해킹(사이드채널/프로빙) 방어 |
| 핵심 특징 | NIST SP 800-193 PFR 및 하드웨어 RoT | SELinux, ASLR, 커널 무결성 보호 | WAF, 입력값 검증, 암호화 통신 | PUF, 글리치 감지, 탬퍼 실링 |
| 한계 | 개발 주기 길고 칩 레벨 지원 필수 | 펌웨어 레벨 감염 시 전면 무력화 | 상위 레이어에만 국한(인프라 무방비) | 설계 단가 상승 및 양산 복잡도 |

#### 한줄 요약
- 네 계층은 위로 갈수록 대응이 빠르고 아래로 갈수록 무너졌을 때의 파급이 크므로, 투자 우선순위는 사고 빈도가 아니라 복구 불가능성으로 정해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **아웃오브밴드(OOB, Out-of-Band) 관리망**: 업무 데이터 트래픽과 물리적으로 분리되어 서버 관리(BMC) 트래픽만 전담하는 독립 전용 네트워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 관리 포트 노출로 원격 관리 계층 침해 | **아웃오브밴드(OOB, Out-of-Band) 관리망** 분리와 강한 인증 적용 | 업무망에서 관리 계층으로의 직접 접근 차단 |
| 서드파티 구성요소의 공급망 취약점 유입 | 표준 형식 SBOM 구축과 자동 취약점 스캐닝 연계 | 패치 대상 구성요소의 신속한 식별 |
| 플래시에 직접 악성 펌웨어를 기록하는 물리 공격 | 하드웨어 버스 가드 장착과 쓰기 방지 핀 고정 | 물리 변조와 루트킷 덮어쓰기 차단 |
| 업데이트 중 전원 차단으로 부팅 불능 | 이중 플래시와 부팅 성공 확인 기반 자동 복귀 | 손상 이미지 활성화 차단과 복구 경로 확보 |

#### 한줄 요약
- 네 위협 중 둘이 조직 밖에서 들어오는 경로이므로, 펌웨어 보안은 자사 코드 품질이 아니라 부품과 관리망 경계에 대한 통제 문제로 다뤄야 한다.

## Ⅶ. 결론

- 업데이트 가능한 핵심 플랫폼은 보호·탐지·복구를 독립 경로로 분리하고 복구 이미지에도 동일한 서명·버전 검증을 적용하며, 구성요소 명세는 취약점 대응에 신뢰 뿌리는 부팅 전 검증과 쓰기 통제에 각각 역할을 나눔

#### 한줄 요약
- 이 영역의 대책은 사고를 막는 비용이 아니라 사고 뒤 장비를 폐기하지 않아도 되는 비용으로 계산해야 하며, 그때 비로소 전용 칩의 값이 설명된다.
