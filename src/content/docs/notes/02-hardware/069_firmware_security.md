## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **펌웨어(Firmware)**: 하드웨어 초기화, 부팅, 전력 및 저수준 제어를 담당하는 불휘발성 메모리 내 소프트웨어(UEFI/BIOS, BMC 등).
- **플랫폼 펌웨어 복원력(PFR, Platform Firmware Resiliency)**: NIST SP 800-193 지침의 보호·탐지·복구 원칙으로 플랫폼 펌웨어를 방어하는 체계.

</details>

- 정의/개념: 하드웨어와 OS 사이 최하위 펌웨어(UEFI/BMC)의 변조를 막고 회복력을 보장하는 **플랫폼 펌웨어 복원력(NIST SP 800-193)** 체계
- 배경/필요성: OS 상위 보안 통제를 무력화하는 스텔스 부트킷 및 공급망(Supply Chain) 공격 방어 필요

#### 한줄 요약
- OS보다 아래에서 작동해 백신에 걸리지 않는 펌웨어 해킹을 막고, 오염 시 자동으로 정상 복구하는 보안 체계다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NIST SP 800-193 3대 원칙**: 보호(Protect, 불법 쓰기 차단), 탐지(Detect, 무결성 훼손 감지), 복구(Recover, 정상 이미지 자동 복원).
- **SBOM(Software Bill of Materials)**: 펌웨어 내부에 포함된 오픈소스 및 서드파티 라이브러리의 버전과 구성 목록을 명시한 자재명세서.

</details>

- **NIST SP 800-193 3원칙(Protect, Detect, Recover)** 기반 복원력 설계
- 펌웨어 구성요소와 취약 버전을 추적하는 **SBOM** 연계
- 하드웨어 격리 RoT 칩(PFR MCU/FPGA) 기반 **아웃오브밴드(Out-of-Band) 독립 감시**

#### 한줄 요약
- 보호·탐지·복구 경로를 분리해 변조된 활성 이미지를 검증된 복구 이미지로 되돌린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: 서버의 전원, 쿨링, 원격 KVM 콘솔을 독립적으로 제어하는 서버 관리 전용 보조 프로세서.
- **PFR RoT(Platform Root of Trust)**: 메인 CPU와 독립적으로 동작하며 SPI 플래시 메모리의 펌웨어를 상시 검증하는 전용 보안 하드웨어.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ NIST SP 800-193 기반 플랫폼 펌웨어 복원력(PFR) 아키텍처    │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 독립 하드웨어 RoT (PFR FPGA / 보안 MCU)               │  │
│  │  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │  │
│  │  │ 1. 보호(Protect)│ │ 2. 탐지(Detect)│ │ 3. 복구(Recover) │ │
│  │  │ (SPI 쓰기 잠금)│ │ (SHA-256/ECDSA)│ │ (A/B 자동 롤백)│ │
│  │  └──────────────┘  └──────────────┘  └──────────────┘ │  │
│  └──────────┬───────────────────────┬────────────────────┘  │
│             │ (SPI 버스 필터링)     │                       │
│             ▼                       ▼                       │
│  ┌───────────────────────┐ ┌───────────────────────────┐    │
│  │ 주 플래시 (Active SPI)│ │ 백업 플래시 (Recovery SPI) │    │
│  │ (UEFI BIOS / BMC FW)  │ │ (골든 이미지 무결성 보관) │    │
│  └───────────────────────┘ └───────────────────────────┘    │
│             ▲                                               │
│             │ (부팅 제어)                                   │
│  ┌──────────┴────────────┐ ┌───────────────────────────┐    │
│  │ 호스트 CPU (x86/ARM)  │ │ 관리 컨트롤러 (BMC)       │    │
│  └───────────────────────┘ └───────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: PFR RoT가 SPI 플래시 버스 트래픽을 가로채 서명되지 않은 불법 쓰기를 차단하고 변조 감지 시 백업 롬으로 복구

| 구성요소 | 책임 |
|:---|:---|
| PFR RoT 보안 컨트롤러 | 메인 시스템 부팅 전 SPI 플래시 펌웨어의 전자서명 검증 및 버스 필터링 |
| 활성 플래시 (Active Flash) | 현재 시스템이 실행하는 주 UEFI/BIOS 및 BMC 펌웨어 바이너리 저장 |
| 복구 플래시 (Recovery Flash) | 변조 시 복원에 사용할 읽기 전용 공장 출하 골든(Golden) 복구 이미지 보관 |
| 베이스보드 관리기 (BMC) | 원격 서버 관리용 독립 칩셋으로, 전용 관리망 격리 및 펌웨어 보호 필수 |
| 펌웨어 SBOM 관리자 | 펌웨어 내 취약한 오픈소스(Log4j, OpenSSL 등) 컴포넌트를 식별 추적 |

#### 한줄 요약
- 독립 PFR 보안 칩, 활성/복구 이중 플래시, 보호/탐지/복구 엔진, SBOM 관리자가 통합 방어망을 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **골든 이미지(Golden Image)**: 복구에 사용할 서명·버전이 검증되고 별도 쓰기 정책으로 보호된 기준 펌웨어 이미지.

</details>

```text
시스템 전원 인가 (Power-On)
      │
      ▼
1. 부팅 차단
      │
      ▼
2. 사전 무결성 검증
      ├── [검증 통과] ───────────────────────────────┐
      └── [변조 감지] ──► 3. 변조 시 자동 치유     │
                             │
                             ▼
4. 침해 이벤트 로깅 및 복원 이미지 재검증
                             │
                             ▼
5. 안전 부팅 속행 ◄─────────────────────────────────┘
```

**동작 원리**

1. **부팅 차단**: 전원 투입 즉시 PFR RoT가 CPU의 리셋 핀을 잡아 부팅을 일시 정지시킴
2. **사전 무결성 검증**: Active 롬에 저장된 UEFI 및 BMC 펌웨어의 전자서명을 칩 내부 공개키로 검증
3. **변조 시 자동 치유**: 펌웨어 변조가 확인되면 Recovery 롬의 골든 이미지를 Active 롬에 즉시 플래싱
4. **침해 이벤트 로깅**: 하드웨어 불휘발성 이벤트 로그에 변조 발생 시각과 공격 유형 기록
5. **안전 부팅 속행**: 검증된 활성 이미지에서 CPU·BMC 리셋을 해제해 부팅 진행

#### 한줄 요약
- 부팅 정지 → 펌웨어 무결성 검증 → 변조 감지 시 골든 롬 자동 복원 → 재검증 → 정상 부팅 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 보안 계층 영역 | 펌웨어 보안 (UEFI/BMC) | OS 커널 보안 | 애플리케이션 보안 | 물리 하드웨어 보안 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 최하위 시스템 신뢰 기반 구축 | 운영체제 런타임 메모리 보호 | 웹/DB 비즈니스 서비스 보호 | 칩 물리 해킹(사이드채널/프로빙) 방어 |
| 핵심 특징 | NIST SP 800-193 PFR 및 하드웨어 RoT | SELinux, ASLR, 커널 무결성 보호 | WAF, 입력값 검증, 암호화 통신 | PUF, 글리치 감지, 탬퍼 실링 |
| 한계 | 개발 주기 길고 칩 레벨 지원 필수 | 펌웨어 레벨 감염 시 전면 무력화 | 상위 레이어에만 국한(인프라 무방비) | 설계 단가 상승 및 양산 복잡도 |

#### 한줄 요약
- 모든 보안의 기초는 펌웨어 보안이며, 이것이 무너지면 상위 OS와 애플리케이션 보안은 완전히 무력화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **아웃오브밴드(OOB, Out-of-Band) 관리망**: 업무 데이터 트래픽과 물리적으로 분리되어 서버 관리(BMC) 트래픽만 전담하는 독립 전용 네트워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| BMC 포트 노출에 따른 **원격 관리면 침해** | OOB 관리망 분리와 강한 관리자 인증·접근 제어 적용 | 업무망·인터넷에서 BMC로의 직접 접근 제한 |
| 서드파티 펌웨어 라이브러리의 **공급망 제로데이 취약점(Supply Chain Attack)** | **CycloneDX / SPDX 기반 펌웨어 SBOM** 구축 및 자동 취약점 스캐닝 | 패치 필요 컴포넌트 실시간 식별 |
| 플래시 롬 직접 쓰기를 통한 **SPI 플래시 악성 펌웨어 플래싱** | **하드웨어 SPI 버스 가드(PFR)** 장착 및 칩셋 쓰기 방지(WP) 핀 고정 | 물리적 변조 및 루트킷 덮어쓰기 차단 |
| 펌웨어 업데이트 중 전원 차단에 따른 **부팅 불능** | A/B 플래시와 부팅 성공 확인·실패 횟수 기반 롤백 적용 | 손상 이미지 활성화 방지와 복구 경로 확보 |

#### 한줄 요약
- OOB 관리망을 격리하고, SBOM으로 공급망을 추적하며, PFR 칩과 A/B 플래시로 자동 복구 체계를 갖춘다.

## Ⅶ. 결론

- 업데이트 가능한 핵심 플랫폼은 **보호·탐지·복구**를 분리하고 복구 이미지도 서명·버전 검증
- SBOM은 취약 구성요소 대응에, 하드웨어 RoT는 부팅 전 검증·쓰기 통제에 역할 분담

#### 한줄 요약
- 펌웨어 레벨의 보호, 탐지, 복구 메커니즘을 하드웨어 RoT와 결합하여 OS 침해 이전의 근원적 신뢰성을 확보해야 한다.
