## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령을 해석하고 연산과 메모리 제어를 수행하는 처리 장치이다.
- **입출력(Input/Output, I/O)**: 컴퓨터와 장치 사이에서 데이터를 읽거나 쓰는 작업이다.
- **퍼시스턴트 메모리(Persistent Memory)**: CPU가 바이트 주소로 직접 접근하며 전원 차단 뒤에도 값을 보존하는 메모리이다.
- **바이트 주소 지정(Byte Addressability)**: CPU가 블록 I/O 대신 개별 메모리 주소 단위로 데이터를 읽고 쓸 수 있는 성질이다.
- **재시작 지연(Restart Latency)**: 장애 후 저장장치에서 상태를 다시 읽고 자료구조를 복원하는 데 걸리는 시간이다.

</details>

- 정의/개념: **퍼시스턴트 메모리**는 **CPU**가 메모리 주소로 직접 접근하고 전원이 끊겨도 값을 보존하는 메모리이다.
- 배경/필요성: DRAM의 상태는 전원 차단 시 사라지고 SSD는 블록 I/O 계층을 거치므로 대규모 상태를 다시 적재하는 재시작 시간이 길어진다.

#### 한줄 요약

- **퍼시스턴트 메모리**는 **바이트 주소 지정**과 비휘발성을 결합하여 **재시작 지연**을 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **직접 접근(Direct Access, DAX)**: 운영체제 페이지 캐시를 거치지 않고 영속 영역을 프로세스 주소 공간에 매핑하는 방식이다.
- **캐시 라인 플러시(Cache-line Flush)**: CPU 캐시의 변경된 라인을 메모리와 영속 경계 쪽으로 내보내는 명령이다.
- **메모리 펜스(Memory Fence)**: 앞선 메모리 쓰기가 요구한 순서로 완료되도록 보장하는 명령이다.
- **장애 정합성(Crash Consistency)**: 임의 시점의 장애 뒤에도 완료된 상태만 채택하고 미완료 갱신을 안전하게 복원하는 성질이다.

</details>

- **직접 접근**: 페이지 캐시를 거치지 않고 바이트 단위로 읽고 쓴다.
- **캐시 라인 플러시**와 **메모리 펜스**: 영속 도달과 쓰기 순서를 보장한다.
- **장애 정합성**: 로그로 완료된 트랜잭션만을 복구한다.

#### 한줄 요약

- **캐시 라인 플러시**와 **메모리 펜스** 및 커밋 순서로 **장애 정합성**을 보장하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **영속 자료구조(Persistent Data Structure)**: 재시작 후에도 포인터와 상태를 복구하여 계속 사용할 수 있게 설계한 자료구조이다.
- **DAX 매핑(DAX Mapping)**: 영속 파일이나 장치 영역을 애플리케이션의 가상 주소 공간에 직접 연결한 매핑이다.
- **영속성 영역(Persistence Domain)**: 쓰기가 이 경계에 도달하면 전원 차단 뒤에도 데이터가 보존되는 하드웨어 범위이다.
- **캐시•영속 제어(Cache•Persistence Control)**: 플러시와 펜스로 쓰기 도달 순서를 보장하는 구성이다.

</details>

```text
[영속 자료구조] -- [DAX 매핑] -- [캐시•영속 제어] -- [영속성 영역]
```

선의 의미: 애플리케이션 자료구조의 주소 매핑부터 캐시 영속 제어와 비휘발 경계까지 결합된 정적 메모리 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 영속 자료구조 | 로그•커밋 관리 |
| DAX 매핑 | 주소 공간 연결 |
| 캐시•영속 제어 | 플러시•순서 보장 |
| 영속성 영역 | 전원 후 데이터 보존 |

#### 한줄 요약

- **DAX 매핑**과 **캐시•영속 제어**로 **영속 자료구조**와 **영속성 영역**을 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **트랜잭션(Transaction)**: 여러 데이터 갱신을 하나의 성공 또는 실패 단위로 묶는 작업이다.
- **커밋 표식(Commit Record)**: 새 버전의 모든 필수 데이터가 영속되었음을 나타내는 메타데이터이다.
- **순서 보존 쓰기(Ordered Persistence)**: 로그와 본 데이터 및 커밋 표식이 복구 규칙에 맞는 순서로 영속되게 하는 처리이다.
- **복구 불변식(Recovery Invariant)**: 장애 시점과 무관하게 복구 후 반드시 성립해야 하는 데이터 조건이다.
- **복구 로그 기록**: 갱신 전 값이나 재실행 정보를 먼저 저장하는 단계이다.
- **로그 플러시·펜스**: 로그를 본 데이터보다 먼저 영속성 영역에 도달시키는 단계이다.
- **본 데이터 기록·플러시**: 자료구조 변경값을 기록하고 영속 경계까지 내보내는 단계이다.
- **커밋 표식 영속**: 필수 데이터의 영속 완료 뒤 트랜잭션 완료 표식을 저장하는 단계이다.
- **복구 상태 판정**: 재시작 시 커밋 여부에 따라 변경을 채택하거나 복원하는 단계이다.

</details>

```text
[트랜잭션 갱신 요청]
          │
          ▼
1. 복구 로그 기록
          │
          ▼
2. 로그 플러시•펜스
          │
          ▼
3. 본 데이터 기록•플러시
          │
          ▼
4. 커밋 표식 영속
          │
    ┌─────┴──────────┐
    │ 정상 완료      │ 전원 장애
    ▼                ▼
[I/O 완료 반환]  5. 복구 상태 판정
                     ┌──┴──────────┐
                     │ 커밋 완료   │ 미완료
                     ▼             ▼
                 [상태 채택]   [로그 복원]
```

### 동작 원리

1. **복구 로그 기록**: 갱신 전 값이나 재실행 정보를 로그에 기록하여 중단된 변경을 복구할 근거를 만든다.
2. **로그 플러시•펜스**: 본 데이터보다 로그가 먼저 영속성 영역에 도달하도록 캐시 라인을 플러시하고 순서를 보장한다.
3. **본 데이터 기록•플러시**: 자료구조의 변경값을 기록한 뒤 해당 캐시 라인이 영속성 영역에 도달하게 한다.
4. **커밋 표식 영속**: 본 데이터의 영속 완료가 보장된 다음 트랜잭션 완료 표식을 기록한다.
5. **복구 상태 판정**: 재시작 시 커밋 표식이 있는 변경은 채택하고 미완료 변경은 로그 방식에 따라 취소하거나 재실행한다.

#### 한줄 요약

- **순서 보존 쓰기**로 로그→데이터→커밋 순서를 지켜야 장애 후 완료된 변경과 미완료 변경을 정확히 구분할 수 있다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **동적 임의 접근 메모리(Dynamic Random-access Memory, DRAM)**: CPU가 바이트 단위로 접근하는 휘발성 작업 메모리이다.
- **반도체 드라이브(Solid-state Drive, SSD)**: 플래시 기반 비휘발 대용량 블록 저장장치이다.
- **블록 계층 동기화(Block-layer Synchronization)**: 파일시스템과 운영체제 및 장치 캐시를 거쳐 데이터 영속 완료를 확인하는 처리이다.

</details>

| 저장 매체 | 퍼시스턴트 메모리 | DRAM | SSD |
|:---|:---|:---|:---|
| 적용 기준 | 직접 갱신•빠른 재시작 | 실행 중 작업 데이터 | 대용량•단순 영속 저장 |
| 핵심 특징 | 바이트 접근•비휘발 | 바이트 접근•휘발 | 블록 접근•비휘발 |
| 한계 | 플러시 순서•복구 복잡성 | 전원 차단 시 데이터 소실 | **블록 계층 동기화** 비용 |

#### 한줄 요약

- 빠른 재시작 상태에는 영속 메모리, 휘발 작업 데이터에는 DRAM, 대용량 보관 데이터에는 SSD를 배치한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **부분 갱신(Partial Update)**: 트랜잭션을 이루는 여러 쓰기 가운데 일부만 영속되어 서로 맞지 않는 상태이다.
- **정전 주입 시험(Power-failure Injection Test)**: 갱신 중 전원을 강제로 차단한 뒤 복구 결과와 불변식을 확인하는 시험이다.
- **상대 포인터(Relative Pointer)**: 고정 가상 주소 대신 기준점으로부터의 거리로 객체 위치를 나타내는 참조이다.
- **매체 마모(Media Wear)**: 반복 쓰기로 비휘발 저장 셀의 수명과 신뢰성이 줄어드는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **커밋 표식**이 데이터보다 먼저 영속돼 **부분 갱신** 노출 | **순서 보존 쓰기** 적용 | **장애 정합성** 유지 |
| **영속성 영역**을 잘못 가정해 정전 뒤 쓰기 소실 | 경계 확인과 **정전 주입 시험** | **복구 불변식** 검증 |
| 재시작 주소가 바뀌어 절대 포인터의 참조 단절 | **상대 포인터**와 재연결 검사 | 객체 그래프 복구 |
| **매체 마모**와 비트 오류로 영속 데이터 손상 | 체크섬•복제•마모 감시 | 데이터 내구성 향상 |

#### 한줄 요약

- **캐시 라인 플러시**와 **메모리 펜스** 순서를 **정전 주입 시험**으로 검증한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **재시작 상태(Restart State)**: 장애 후 즉시 복구하여 이전 실행을 이어 가야 하는 애플리케이션 데이터이다.
- **휘발 작업 데이터(Volatile Working Data)**: 실행 중에만 필요하고 전원 차단 뒤 보존할 필요가 없는 임시 상태이다.
- **보관 데이터(Archival Data)**: 큰 용량과 장기 보존이 중요하고 블록 접근 지연을 허용하는 데이터이다.
- **메모리 배치 기준**: 재시작 속도와 휘발 허용 여부 및 용량에 따라 저장 매체를 고르는 기준이다.

</details>

- **메모리 배치 기준**에 따라 **재시작 상태**는 **퍼시스턴트 메모리**, **휘발 작업 데이터**는 **DRAM**, **보관 데이터**는 **SSD**를 선택한다.

#### 한줄 요약

- 빠르게 복구해야 하는 **재시작 상태**는 퍼시스턴트 메모리, 영속성이 필요 없는 **휘발 작업 데이터**는 DRAM에 배치한다.
