## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **퍼시스턴트 메모리(Persistent Memory, PMEM)**: 시스템 메모리 버스(DDR/CXL)에 직접 장착되어 CPU가 바이트 단위(Byte-Addressable)로 나노초 수준에서 직접 접근하면서도, 전원 차단 시 데이터가 영구 보존되는 비휘발성 메모리.
- **재기동 지연시간(Restart Latency)**: 시스템 불시 재부팅 시 수 테라바이트(TB) 규모의 인메모리 데이터베이스(IMDB)를 SSD에서 DRAM으로 다시 적재하는 데 소요되는 시간.

</details>

- 정의/개념: DRAM급의 초고속 바이트 단위 주소 접근성과 NAND 플래시의 비휘발성을 결합한 **퍼시스턴트 메모리**(PMEM / Storage-Class Memory) 아키텍처
- 배경/필요성: DRAM 기반 인메모리 DB는 정전 때마다 전체 데이터셋을 스토리지에서 다시 올려야 해 복구 시간이 용량에 비례하며 **즉각 복구 불가**로 남으므로, 바이트 단위 접근성을 유지하면서 전원이 끊겨도 내용이 남는 매체를 메모리 버스 계층에 두어 재적재 자체를 생략할 필요

#### 한줄 요약
- 나노초 단위의 바이트 직접 접근성과 비휘발성을 동시에 제공하여 인메모리 데이터베이스의 즉각적 복구를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **직접 접근 모드(Direct Access, DAX)**: 운영체제 커널의 페이지 캐시 및 블록 I/O 드라이버 스택을 완전히 우회하여 유저 애플리케이션이 PMEM 물리 주소를 mmap 포인터로 직결 접근하는 기술.
- **clwb / sfence 명령어**: CPU 캐시에 머무는 변경된 캐시 라인을 비휘발성 영속성 도메인으로 강제 방출(clwb)하고 메모리 쓰기 순서를 직렬화(sfence)하는 어셈블리 명령어.

</details>

- OS 오버헤드 배제: **DAX**(Direct Access) 매핑을 통해 커널 페이지 복사 및 파일시스템 블록 오버헤드 없이 포인터 직접 역참조
- 명시적 영속 쓰기 순서: **clwb** 및 **sfence** 명령어를 조합하여 정전 시에도 크래시 정합성(Crash Consistency) 보장
- 비동기 영속화 보장: 시스템 정전 시 커패시터 전력으로 쓰기 큐(WPQ) 데이터를 PMEM 미디어로 플러시하는 **ADR** 회로 내장

#### 한줄 요약
- DAX로 OS I/O 스택을 우회하고 clwb/sfence 명령어로 캐시 플러시 쓰기 순서를 제어하여 나노초 단위 영속성을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PMDK(Persistent Memory Development Kit)**: 비휘발성 메모리 상에서 트랜잭션 원자성과 메모리 풀 할당을 지원하는 오픈소스 표준 C/C++ 라이브러리 슈트.
- **ADR(Asynchronous DRAM Refresh)**: 전원 상실(Power Loss) 감지 시 백업 커패시터 전력을 활용하여 CPU 메모리 컨트롤러 쓰기 큐(WPQ)의 잔여 데이터를 PMEM 미디어로 강제 플러시하는 하드웨어 회로.

</details>

```text
[퍼시스턴트 메모리(PMEM) 하드웨어 및 소프트웨어 계층]
├── 사용자 애플리케이션 계층
│   └── PMDK 라이브러리 (libpmemobj 기반 영속 자료구조)
├── 운영체제 커널 계층
│   └── DAX 드라이버 (Direct Access, 페이지 캐시 우회)
├── CPU 명령어 집합 계층
│   └── clwb 및 sfence (캐시 방출 및 쓰기 순서 직렬화)
└── 영속성 도메인 (Persistence Domain)
    ├── ADR 하드웨어 회로 (정전 시 자동 플러시)
    └── PMEM 물리 미디어 (3D XPoint, STT-MRAM, CXL.mem)
```

선의 의미: 가지(`├──`, `└──`)는 PMEM 계층별 소속 및 포함 관계; clwb와 sfence 명령어가 캐시 데이터를 ADR로 보호되는 영속성 도메인으로 밀어넣음

| 구성요소 | 책임 |
|:---|:---|
| PMDK 라이브러리 | **트랜잭션**과 원자적 메모리 할당 |
| DAX 드라이버 | 페이지 캐시를 우회한 **물리 메모리 직결** |
| clwb / sfence | 캐시 방출과 **메모리 쓰기 순서** 직렬화 |
| ADR 하드웨어 회로 | 정전 시 **쓰기 큐 자동 플러시** |
| PMEM 물리 미디어 | 전원 차단 후 **비휘발성 데이터** 보존 |

#### 한줄 요약
- clwb로 캐시 밖까지 밀어낸 데이터도 아직 쓰기 큐에 남아 있으므로 그 마지막 구간만은 소프트웨어가 아닌 ADR 회로가 정전 순간에 떠맡고, 응용이 직접 짜야 할 원자적 갱신 절차는 PMDK 트랜잭션 계층이 대신 보장한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **순서 보존 쓰기(Ordered Persistence)**: 로그 기록 ➔ 플러시 ➔ 본 데이터 기록 ➔ 플러시 ➔ 커밋 플래그 설정의 순서를 엄격히 지켜 정전 시에도 원자성을 보장하는 패턴.

</details>

```text
애플리케이션: PMEM 트랜잭션 데이터 쓰기 요청
      │
      ▼
1. WAL(Write-Ahead Logging) 메타데이터를 PMEM 버퍼에 기록
      │
      ▼
2. clwb로 로그 캐시 라인을 방출하고 sfence로 영속화 순서 확정
      │
      ▼
3. 실제 비즈니스 데이터 기록 후 clwb 방출
      │
      ▼
4. 트랜잭션 커밋 플래그 기록 및 sfence 인가
      │
      ▼
정전 발생 시 커밋 플래그 기반 복구
   ├── [커밋 완료] ── 재부팅 후 데이터 즉시 사용 (복구 지연 0)
   └── [미완료 상태] ─ WAL 로그 참조하여 롤백(Undo) 수행
```

분기 결과: **순서 보존 쓰기**를 통해 재부팅 시 재적재 없이 즉각적인 트랜잭션 복구 보장

#### 한줄 요약
- clwb와 sfence로 쓰기마다 순서를 강제하는 비용을 치르는 대신, 정전 뒤 데이터를 디스크에서 다시 적재하던 복구 단계 자체를 없앤다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CXL.mem(Compute Express Link Memory)**: 호스트 CPU가 PCIe Gen5/Gen6 물리 계층 상에서 풀링된 비휘발성 PMEM 메모리를 바이트 단위로 직접 접근하는 표준 프로토콜.

</details>

| 메모리 및 저장 매체 | 퍼시스턴트 메모리 (PMEM) | DRAM (동적 램) | All-Flash NVMe SSD |
|:---|:---|:---|:---|
| 데이터 접근 단위 | **바이트 단위** (Byte-Addressable) | 바이트 단위 (Byte-Addressable) | 블록 단위 (4KB Page/Block) |
| 읽기/쓰기 지연시간 | 수십 ~ 수백 나노초 | **수십 나노초** (ns) | 수십 마이크로초 ($\mu\text{s}$) |
| 데이터 영속성 | **비휘발성** (영구 보존) | 휘발성 (전원 차단 시 소멸) | 비휘발성 (NAND 플래시) |
| 주 용도 | 인메모리 DB, **트랜잭션 WAL** | 프로세스 작업 메모리, CPU 캐시 | 대규모 파일 시스템, 영구 스토리지 |
| 재부팅 시 복구 시간 | **초 단위 즉각 복구** | 수십 분 이상 (SSD에서 재적재) | 해당 없음 (스토리지 자체) |

#### 한줄 요약
- PMEM은 DRAM의 나노초 속도와 SSD의 영속성을 결합하여 인메모리 DB의 재기동 지연을 사실상 0으로 단축한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **타입 지정 객체 식별자(Typed OID, TOID)**: ASLR(주소 공간 무작위화) 환경에서 재부팅 시 메모리 매핑 가상 주소가 바뀌어도 유효성을 유지하도록 메모리 풀 ID와 상대 오프셋으로 관리하는 스마트 포인터.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CPU 캐시에 머무는 미플러시 데이터의 불시 정전 유실 | **clwb/sfence 플러시** 및 ADR 연동 | 정전 시 잔여 데이터 영속화 |
| 시스템 재부팅 시 ASLR로 인한 절대 가상 포인터 무효화 | **상대 오프셋**(TOID) 구조체 적용 | 가상 주소 재매핑 무결성 유지 |
| 크래시 시 부분 쓰기(Torn Write)로 인한 자료구조 깨짐 | **PMDK 트랜잭션** 엔진 적용 | 미완료 트랜잭션 자동 롤백 보장 |

#### 한줄 요약
- 실무에서는 clwb/ADR로 정전 유실을 막고, TOID로 포인터를 보호하며, PMDK 트랜잭션으로 원자성을 보장한다.

## Ⅶ. 결론

- 인메모리 DB 영속성 보장 시 **DAX**와 **clwb/ADR** 기반 아키텍처 채택

#### 한줄 요약
- 퍼시스턴트 메모리는 메모리와 스토리지의 경계를 허물어 고성능 시스템의 재기동 지연을 없애는 차세대 메모리 아키텍처다.
