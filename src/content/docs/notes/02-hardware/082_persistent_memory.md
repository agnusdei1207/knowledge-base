## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PMEM(Persistent Memory, 퍼시스턴트 메모리)**: DRAM 버스에 직접 장착되어 바이트 단위로 고속 읽기/쓰기가 가능하면서 전원 차단 시에도 데이터가 영구 보존되는 비휘발성 메모리.
- **Byte-Addressability(바이트 주소 지정)**: 4KB 블록 단위 I/O 없이 CPU가 단일 바이트 단위로 메모리 포인터를 통해 직접 로드/스토어(Load/Store) 명령을 수행하는 특성.
- **Restart Latency(재기동 지연시간)**: 시스템 재부팅 시 수 TB의 인메모리 데이터베이스를 SSD에서 DRAM으로 다시 적재하는 데 소요되는 시간.

</details>

- 정의/개념: DRAM과 유사한 나노초($\text{ns}$) 단위 바이트 주소 접근성(Byte-Addressability)과 NAND 플래시의 비휘발성(Non-Volatile) 특성을 동시에 제공하는 영속성 메모리 하드웨어 아키텍처
- 배경/필요성: 서버 정전 또는 재기동 시 스토리지로부터 대용량 데이터를 메모리에 다시 적재하는 **재시작 지연(Restart Latency)을 제거하고, 인메모리 DB 및 영속 데이터 구조의 초저지연 I/O 실현**

#### 한줄 요약

- 나노초 단위 바이트 접근성과 비휘발성을 결합한 **하이브리드 영속 메모리(PMEM) 아키텍처**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DAX(Direct Access)**: 커널의 페이지 캐시 및 블록 I/O 계층을 완전히 우회하여 유저 공간 애플리케이션이 PMEM 물리 주소를 직접 mmap하여 접근하는 모드.
- **clwb / sfence**: CPU 캐시에 머물러 있는 변경 데이터를 영속성 도메인으로 강제 밀어내고(clwb) 순서를 고정(sfence)하는 어셈블리 명령어.
- **Crash Consistency(장애 정합성)**: 전원 차단이나 시스템 크래시 발생 시에도 데이터 구조가 손상되지 않고 정상 복구 가능한 상태를 유지하는 성질.

</details>

- OS 커널의 페이지 캐시 복사 및 블록 디바이스 드라이버 오버헤드를 제거하는 **DAX(Direct Access) 초저지연 매핑**
- CPU 캐시 계층의 휘발성 데이터를 비휘발성 영역으로 강제 방출하는 **clwb(Cache Line Write Back) 및 sfence 명령어 제어**
- 전원 장애 시에도 데이터 유실 없이 즉각적인 재기동을 보장하는 **장애 정합성(Crash Consistency) 및 재시작 지연 극소화**

#### 한줄 요약

- **DAX(Direct Access) 커널 우회·clwb/sfence 명시적 영속화(Flushing)·Crash Consistency 장애 정합성**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ADR(Asynchronous DRAM Refresh)**: 전원 상실 시 배터리/슈퍼캐퍼시터 전력으로 메모리 컨트롤러 쓰기 큐(WPQ)의 데이터를 PMEM으로 플러시하는 하드웨어 생존 회로.
- **PMDK(Persistent Memory Development Kit)**: libpmem, libpmemobj 등 트랜잭션과 메모리 풀 관리를 지원하는 인텔 오픈소스 C/C++ 라이브러리 슈트.

</details>

```text
[ PMEM 하드웨어 계층 및 영속화 제어 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 영속 애플리케이션 (PMDK libpmemobj 트랜잭션 라이브러리) │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ DAX mmap() 직결 바이트 포인터 접근 ]
┌──────────────────────────────┴──────────────────────────────┐
│ 2. CPU 코어 및 캐시 계층 (L1 / L2 / L3 캐시 : 휘발성 영역) │
│  └─ 3. 캐시 제어 명령어 (clwb ──> sfence 순서 보존)          │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 메모리 컨트롤러 쓰기 큐 (WPQ) ]
┌──────────────────────────────┴──────────────────────────────┐
│ 4. 플랫폼 영속성 도메인 (ADR 회로 + PMEM 비휘발성 미디어)   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: PMDK 영속 자료구조, DAX 파일시스템 매핑, CPU 캐시 플러시 제어 및 ADR 백업 영속성 도메인 간의 PMEM 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 영속 자료구조 | 데이터가 중간에 박살 나지 않게 **피엠디케이(PMDK)** 라이브러리로 뼈대를 세운 불멸의 자료구조 |
| 다이렉트 억세스(DAX) 매핑 | 커널의 구질구질한 파일시스템(블록 변환)을 무시하고 사용자 프로그램과 메모리를 직통으로 연결하는 고속도로 |
| 캐시•영속 제어 | CPU한테 "**clwb** 뱉어! **sfence** 멈춰!" 하고 호통쳐서 캐시 찌꺼기를 영속 메모리로 강제 이송시키는 지휘관 |
| 영속성 영역 | 전기가 나가는 최후의 순간에도 남은 전력을 쥐어짜서 데이터를 피난시키는 **ADR** 회로와 **퍼시스턴트 메모리** 본체 |

#### 한줄 요약

- **PMDK 영속 라이브러리·DAX 파일시스템 매핑·clwb/sfence 캐시 제어·ADR(Asynchronous DRAM Refresh)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Ordered Persistence(순서 보존 쓰기)**: 로그 기록 $\to$ 플러시 $\to$ 본 데이터 기록 $\to$ 플러시 $\to$ 커밋 플래그 설정의 순서를 엄격히 지켜 정합성을 보장하는 패턴.

</details>

```text
[ PMEM 트랜잭션 쓰기 및 영속화 시퀀스 ]
                         │
                         ▼
   [ 1. 복구용 WAL(Write-Ahead Logging) 메타데이터 기록 ]
                         │
                         ▼
   [ 2. clwb 로 로그 캐시 라인 플러시 후 sfence 로 영속화 순서 확정 ]
                         │
                         ▼
   [ 3. 실제 사용자 데이터 페이로드(Payload) 메모리 기록 및 clwb 실행 ]
                         │
                         ▼
   [ 4. 커밋 플래그(Commit Flag=1) 기록 및 최종 sfence 인가 (순서 보존) ]
                         │
        +────────────────┴────────────────────────+
        │             [ 전원 차단 발생 여부 ]      │
        │             /                         \ │
        │        [ 정상 완료 ]               [ 정전 발생 ]
        │           │                             │
        │     트랜잭션 종결              5. 재부팅 시 커밋 플래그
        │     및 성공 반환                  유무에 따라 Rollback / Commit
        +─────────────────────────────────────────+
```

**동작 원리**

1. **WAL 로깅**: 변경할 메모리 주소와 이전/이후 값을 포함하는 저널 로그를 PMEM에 기록
2. **로그 영속화**: clwb 명령으로 로그 캐시 라인을 비휘발성 도메인으로 방출하고 sfence로 직렬화
3. **본 데이터 기록**: 실제 객체 필드를 수정하고 다시 clwb로 메모리 컨트롤러 WPQ로 배출
4. **커밋 확정**: 커밋 플래그를 1로 세팅하고 sfence를 인가하여 트랜잭션 원자적 완료
5. **장애 복구**: 재부팅 시 PMDK 런타임이 커밋 플래그가 없는 미완료 트랜잭션을 식별하여 롤백

#### 한줄 요약

- WAL 로깅 작성 $\to$ **clwb & sfence 로그 영속화 $\to$ 본 데이터 기록 및 플러시 $\to$ 커밋 플래그 영속(Ordered Persistence) $\to$ 장애 복구 정합성 확보**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PMEM vs DRAM vs NVMe SSD**:
  - PMEM: 바이트 단위, 비휘발성, 수백 $\text{ns}$ 지연, 인메모리 DB/WAL
  - DRAM: 바이트 단위, 휘발성, 수십 $\text{ns}$ 지연, 초고속 연산 버퍼
  - NVMe SSD: 블록 단위(4KB), 비휘발성, 수십 $\mu\text{s}$ 지연, 대용량 스토리지

</details>

| 비교 항목 | 퍼시스턴트 메모리 (PMEM : CXL/NVDIMM) | DRAM (동적 램) | NVMe SSD (NAND 플래시) |
|:---|:---|:---|:---|
| 접근 단위 및 지연시간 | 바이트 단위 (Byte-Addressable), 수십~수백 $\text{ns}$ | 바이트 단위 (Byte-Addressable), 수십 $\text{ns}$ | 블록 단위 (Block I/O : 4KB), 수십 $\mu\text{s}$ |
| 데이터 영속성 (비휘발성) | 비휘발성 (전원 차단 시 영구 보존) | 휘발성 (전원 차단 시 데이터 소멸) | 비휘발성 (NAND 플래시 셀 보존) |
| 한계 및 주 적용 분야 | CPU 캐시 플러시 오버헤드 (인메모리 DB/저널) | 재시작 지연 및 용량 확장 한계 (연산 버퍼) | 읽기/쓰기 수명 제한 및 I/O 병목 (대용량 저장) |

#### 한줄 요약

- 바이트 비휘발성은 **PMEM**, 휘발성 최고속은 **DRAM**, 대용량 블록은 **NVMe SSD**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ASLR과 상대 포인터**: 재부팅 시 가상 주소 공간이 바뀌는 ASLR(Address Space Layout Randomization) 환경에서 절대 포인터 대신 메모리 풀 시작점 기준의 상대 오프셋(TOID)을 사용하는 기법.
- **PFI(Power-Failure Injection)**: 소프트웨어 실행 도중 강제로 전원을 차단하여 영속 자료구조의 Crash Consistency를 검증하는 시험 프레임워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CPU 캐시에만 데이터 적어놓고 영속 메모리로 안 보냈는데 갑자기 정전돼서 데이터가 공중분해 되는 대참사 | **clwb**랑 **sfence** 명령어를 순서대로 때려 박고 **ADR** 회로 떡칠해서 전원 꺼지기 직전까지 캐시 멱살 잡고 덤프함 | 영속 완료됐다고 구라 치는 걸 막아내고 전원 사고 시 데이터 유실 없는 무결성 절대 사수 |
| 메모리에 하드코딩된 절대 주소를 적어놨는데 재부팅했더니 OS가 주소(ASLR)를 섞어버려 포인터가 쓰레기 값이 됨 | 시작점에서 얼마나 떨어졌는지(Offset)만 기록하는 상대 포인터 매핑으로 뼈 깎는 코드 리팩토링 강행 | 시스템 껐다 켜서 메모리 방 번호가 다 바뀌어도 포인터가 완벽하게 복원되어 데이터 부활 |
| 비휘발 메모리 쓴답시고 코딩 대충 했더니 전원 나갔다 오면 DB 순서가 다 꼬여서 정합성이 와해되는 지옥문 개방 | 검증된 **PMDK** 라이브러리 떡칠하고 전원선 강제로 뽑아보는 **파워 페일루어 인젝션**으로 극한 테스팅 | 미친 듯이 껐다 켜도 데이터 순서가 절대 꼬이지 않는 불멸의 **장애 정합성** 완성 |

#### 한줄 요약

- **clwb/sfence 명시적 플러시 및 ADR 회로 연동·상대 오프셋 포인터 매핑(ASLR 대응)·PMDK 기반 장애 주입(PFI) 시험**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL(Compute Express Link) 기반 PMEM 진화**: 인텔 Optane 단종 이후 PCIe 5.0/6.0 상의 CXL.mem 프로토콜을 활용한 이종 비휘발성 풀링 메모리로 생태계 재편 중.

</details>

- 차세대 서버 메모리 계층에서 **CXL 3.0 Type-3 기반 영속 메모리 확장 및 PMDK 기반 저널링 표준 채택**

#### 한줄 요약

- **바이트 접근성과 장애 정합성(Crash Consistency)**을 통한 영속 인메모리 컴퓨팅 구현
