## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **그래픽 처리 장치(Graphics Processing Unit)**: 수천 개의 무식하고 단순한 연산 코어들을 때려 박아, 픽셀이나 행렬 같은 대규모 데이터를 한 번에 밀어버리는 극한의 병렬 처리 특화 프로세서이다.
- **단일 명령 다중 스레드(Single Instruction Multiple Threads)**: 하사관 한 명이 "앞으로 갓!" 하고 외치면 32명의 병사가 각자의 길을 동시에 걸어가듯, 단 하나의 명령어로 수십 개의 스레드를 통제하는 그래픽 처리 장치의 핵심 실행 모델이다.
- **스트리밍 멀티프로세서(Streaming Multiprocessor)**: 스케줄러, 레지스터, 연산 유닛, 그리고 자체 캐시 메모리를 한 몸에 품고 있는 그래픽 처리 장치 내부의 거대한 독립 연산 군단이다.
- **중앙 처리 장치(Central Processing Unit)**: 수십 개의 똑똑한 코어로 똘똘 뭉쳐, 복잡한 분기문과 운영체제 제어 흐름을 번개처럼 빠르게 처리하는 데 특화된 시스템의 총사령관 프로세서이다.

</details>

- 정의: **스트리밍 멀티프로세서**가 수십 개의 스레드를 한 묶음으로 묶어, 동일한 기계어 명령을 서로 다른 독립 데이터에 융단폭격하듯 발행하는 **단일 명령 다중 스레드** 모델
- 배경: 소수의 똑똑한 코어 중심인 **중앙 처리 장치** 구조로는 딥러닝과 그래픽 렌더링에서 쏟아지는 수백만 개의 텐서 및 행렬 병렬 연산을 도저히 감당할 수 없는 한계를 극복하기 위함

#### 한줄 요약

- 수천 개의 스레드를 32개씩 묶어 한 번의 명령으로 통제함으로써, 복잡한 제어 로직을 덜어내고 연산 유닛에 자원을 몰빵하여 대규모 데이터의 처리량을 극대화하는 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: 그래픽 처리 장치가 스레드를 통제하는 최소 단위 묶음으로, 32개의 스레드가 항상 손을 잡고 똑같은 명령어를 동시에 실행해야 하는 운명 공동체이다.
- **지연 은닉(Latency Hiding)**: A 워프가 메모리에서 데이터를 가져오느라 멍때리고 있을 때, 잽싸게 대기 중인 B 워프로 교체해버려 연산기가 1초도 쉬지 않게 만드는 꼼수 기술이다.
- **활성 마스크(Active Mask)**: 워프 안에서 조건문(if-else)을 만나 길이 갈라질 때, 당장 실행하지 않을 스레드들의 입을 틀어막아 조용히 대기시키는 제어용 비트 마스크이다.
- **병합 접근(Coalesced Access)**: 32개의 스레드가 뿔뿔이 흩어져 메모리를 찾지 않고, 32명이 한 번에 뭉쳐서 하나의 거대한 덩어리로 메모리를 퍼 오는 극강의 대역폭 절약 기술이다.
- **점유율(Occupancy)**: 스트리밍 멀티프로세서 안에 꽉꽉 채워 넣을 수 있는 최대 워프 수 대비, 현재 실제로 욱여넣어져 숨 쉬고 있는 활성 워프들의 빽빽한 비율이다.

</details>

- 메모리를 기다리는 잉여 시간을 다른 워프의 실행으로 덮어버려 전송 지연시간을 획기적으로 가리는 **지연 은닉**을 달성함.
- 운명 공동체인 워프 안에서 조건 분기 발생 시, 스레드들의 엇갈린 분기를 통제하기 위해 무식하게 **활성 마스크**를 적용하여 경로를 따로따로 실행함.
- 흩어진 메모리 요청을 한 덩어리로 묶어 대역폭 활용도를 극대화하는 **병합 접근** 및, 연산기를 쉴 틈 없이 돌리기 위한 빽빽한 **점유율** 관리를 지원함.

#### 한줄 요약

- 32명(워프)을 한 묶음으로 굴려 제어를 단순화하고, 멍때릴 틈 없이 다른 묶음으로 교체(지연 은닉)하며, 밥(메모리)을 먹을 때도 한 그릇에 모아 먹게(병합 접근) 하는 군대식 통제 모델이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워프 스케줄러(Warp Scheduler)**: 매 클록 박동마다 칩 안을 째려보다가, 연산 준비가 끝난 워프를 낚아채어 명령어를 파이프라인으로 쏴버리는 무자비한 작업 분배기이다.
- **공유 메모리(Shared Memory)**: 하나의 스트리밍 멀티프로세서 안에 있는 스레드들끼리 바깥 메모리까지 안 나가고 칩 안에서 서로 데이터를 고속으로 돌려쓰는 전용 휴게실(SRAM)이다.
- **전역 메모리(Global Memory)**: 그래픽 처리 장치 보드에 붙어있는 거대한 비디오 메모리(VRAM)로, 용량은 방대하지만 속도가 느려 칩 내부 스레드들에겐 너무나 멀고 험한 영역이다.
- **레벨 2 캐시(Level 2 Cache)**: 수많은 스트리밍 멀티프로세서들이 전역 메모리로 우르르 달려가기 전에 중간에서 트래픽을 모아주고 일관성을 맞춰주는 칩 내부 공용 저수지이다.

</details>

```text
[ 그래픽 처리 장치 스트리밍 멀티프로세서 내부 하드웨어 아키텍처 ]
                        [ 명령 획득 및 워프 스케줄러 디스패처 ]
                                         │
                                         ▼
[ 방대한 레지스터 파일 및 고속 공유 메모리 ] ── [ 수백 개의 산술 논리 연산 유닛 ]
                                         │
                                         ▼
 [ 레벨 2 캐시 일관성 망 ] ── [ 느리지만 거대한 오프칩 전역 메모리 ]
```

| 구성요소 | 책임 |
|:---|:---|
| **워프 스케줄러** | 연산 대기 중인 **워프**들 사이에서 준비된 놈을 재빨리 골라내어 인스트럭션 제어 파이프라인으로 디스패치 |
| 연산 및 로드 스토어 유닛 | 무수히 깔린 실수/정수 연산기로 덧셈과 곱셈을 쳐내고, 메모리 로드 및 스토어 트랜잭션을 물리적 수행 |
| 레지스터 및 **공유 메모리** | 각 스레드의 찰나의 실행 상태를 수만 개의 레지스터에 보관하고, 블록 내 스레드 간 고속 텐서 데이터 공유 |
| **레벨 2 캐시** 및 **전역 메모리** | 모든 **스트리밍 멀티프로세서** 군단 간의 데이터 일관성 교통정리 제공 및 최종 거대 텐서 데이터 영구 저장 |

#### 한줄 요약

- 스케줄러가 채찍질하여 워프를 고르면, 레지스터에서 값을 꺼내 수백 개의 연산기가 갈아버리고, 결과는 다시 공유 메모리나 전역 메모리로 뱉어내는 멈추지 않는 컨베이어 벨트이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스레드 블록(Thread Block)**: 워프들이 수십 개 모여 이룬 더 큰 군단으로, 한 블록에 속한 스레드들은 반드시 같은 스트리밍 멀티프로세서에 배정되어 공유 메모리를 함께 쓸 수 있다.
- **분기 발산(Branch Divergence)**: 운명 공동체인 워프 안에서 'if'와 'else'로 길이 찢어졌을 때, 먼저 'if' 길을 가는 동안 'else' 놈들은 가만히 놀고, 그다음 반대로 노는 처참한 효율 저하 현상이다.

</details>

```text
[ 그래픽 처리 장치 단일 명령 다중 스레드 커널 실행 흐름 제어 ]
                               │
                               ▼
        [ 1. 스레드 블록의 스트리밍 멀티프로세서 물리적 배치 및 자원 락업 할당 ]
                               │
                               ▼
           [ 2. 워프 스케줄러의 준비된 활성 워프 선택 및 명령어 단체 발행 ]
                               │
                               ▼
           [ 3. 인접 스레드 메모리 주소 스캔 및 거대 병합 접근 트랜잭션 ]
                               │
                               ▼
        [ 4. 조건문 조우 시 분기 발산 발생 및 활성 마스크를 통한 경로 개별 실행 ]
                               │
             [ 2~4 과정 무한 반복을 통한 전송 지연 은닉 및 연산 쳐내기 ]
                               │
                               ▼
         [ 5. 블록 내 모든 스레드 실행 완료 시 레지스터 및 메모리 자원 완전 해제 ]
```

### 동작 원리

1. 코어 배치 및 할당: 하드웨어 디스패처가 요구하는 레지스터와 메모리양을 깐깐히 확인하여, 칩 내부에 텅 빈 자리가 있는 멀티프로세서에 **스레드 블록**을 강제 배치함.
2. 준비 워프 명령 발행: **워프 스케줄러**가 밥(메모리)을 기다리는 워프는 버려두고, 당장 뛸 준비가 된 워프를 낚아채어 동일 인스트럭션을 일제히 발행함.
3. 메모리 병합 접근: 전역 메모리로 떠날 때 32명 스레드의 흩어진 인접 주소 패턴을 뭉뚱그려 분석하고, 한 번의 거대한 **병합 접근** 트랜잭션으로 압축하여 퍼 옴.
4. 분기 마스크 실행: if-else 구문으로 운명이 갈리는 **분기 발산** 조우 시, **활성 마스크**를 적용하여 'if' 경로를 먼저 돌리고 'else' 경로를 나중에 따로 돌려 합침.
5. 자원 해제: 무식한 연산 뺑뺑이가 끝나고 블록 내 모든 스레드의 숨통이 끊어지면, 물고 있던 꽉 찬 레지스터와 메모리 자원을 미련 없이 해제함.

#### 한줄 요약

- 블록을 자리에 앉히고, 스케줄러가 놀고 있는 워프를 채찍질하며, 메모리는 뭉쳐서 퍼 오고(병합), 조건문은 따로따로 돌리며(마스크) 일을 끝마치는 숨 가쁜 과정이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 명령 다중 데이터(Single Instruction Multiple Data)**: 중앙 처리 장치 안에 숨어있는 미니 가속기로, 하나의 명령어로 4개나 8개의 배열 데이터를 한 번에 밀어버리는 벡터 연산 체계이다.
- **벡터 레인(Vector Lane)**: 단일 명령 다중 데이터 체계에서 각 배열 요소들이 일렬로 줄지어 들어가 똑같은 연산망치로 두들겨 맞는 1차원 물리적 연산 통로이다.
- **스레드(CPU Thread)**: 운영체제가 만들어낸 가상의 작업 단위로, 자신만의 머릿속(문맥)을 꽉 채우고 복잡한 분기문을 이리저리 타며 자유롭게 뛰어다니는 독립적인 실행자이다.
- **비병합 접근(Uncoalesced Access)**: 32명의 워프 스레드가 메모리를 요청했는데 주소가 중구난방으로 파편화되어, 하나로 묶지 못하고 32번의 끔찍한 메모리 트래픽을 유발하는 지옥 같은 상태이다.

</details>

| 비교 항목 | **단일 명령 다중 스레드** (GPU) | **단일 명령 다중 데이터** (CPU Vector) | **중앙 처리 장치 스레드** (CPU Core) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 수백만 픽셀이나 거대 텐서 행렬처럼 무식하게 대규모 데이터의 동일 연산 가속 시 | 영상 코덱이나 과학 계산의 짧은 수치 행렬 및 배열 벡터 연산 국소 가속 시 | 운영체제 구동, 데이터베이스 트랜잭션 등 극도로 복잡한 제어 흐름 및 직렬 처리 시 |
| 아키텍처 핵심 특징 | 하드웨어 32개 묶음 워프 스케줄링 및 지연 은닉을 통한 극단적인 멍청한 병렬성 | 레지스터에 일렬로 꽉 채운 **벡터 레인** 정렬 기반의 뻣뻣한 병렬성 | 각자 고유한 레지스터와 운영체제 스택을 거느린 독자적 콘텍스트 기반 독립성 |
| 극복해야 할 태생적 한계 | 조건문 떡칠 시 **분기 발산**으로 코어가 멈추며, **비병합 접근** 발생 시 대역폭 지옥에 빠짐 | 메모리에서 긁어올 때 반드시 연속된 주소로 꽉꽉 채워야 하는 엄격한 데이터 패킹 정렬 요구 | 스레드를 하나 만들고 바꿀(문맥 교환) 때마다 운영체제가 개입하여 수천 클록의 엄청난 오버헤드 발생 |

#### 한줄 요약

- 수백만 개의 데이터를 밀어버릴 땐 눈 감고 GPU(SIMT), 작은 배열을 한 큐에 끝낼 땐 CPU 벡터(SIMD), 조건문이 복잡하게 꼬인 똑똑한 제어는 CPU 스레드가 답이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **레인 활용률(Lane Utilization)**: 32명(워프)이 한 조로 묶여 있는데, 분기 발산 때문에 절반은 놀고 절반만 일할 때 낭비되는 자원을 측정한 '진짜로 땀 흘리는 코어의 비율' 지표이다.
- **커널 융합(Kernel Fusion)**: A 작업하고 메모리 쓰고, B 작업하고 메모리 쓰는 멍청한 짓을 막고자, A와 B 커널 함수를 하나로 짬뽕 융합해 칩 내부에서 한 번에 쳐내는 최적화 기법이다.
- **비동기 전송(Asynchronous Transfer)**: 컴퓨터 주인이 그래픽 처리 장치로 데이터를 넘겨주는 동안, 칩은 멍때리지 않고 예전에 받은 데이터를 구워버리며 전송과 연산을 겹쳐 돌리는 야바위 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지독하게 꼬인 조건문(if-else)으로 인한 **분기 발산** 발생 시 반쪽짜리 연산 코어 성능 저하 타격 | 코드 레벨에서 동일 분기 조건끼리 데이터를 미리 재배치 정렬하여 **레인 활용률** 한계 돌파 최적화 | 놀고먹는 비활성 레인 방치 시간을 박멸하고 스레드 단위의 연산 효율 극한 증대 |
| 스레드들이 뿔뿔이 흩어진 주소를 요청하는 치명적인 **비병합 접근** 감지 및 메모리 대역폭 폭발 | 데이터를 구조체 배열(SoA) 형식으로 뜯어고쳐 강제 연속 **병합 접근**이 가능하도록 메모리 맵 재배치 | 수백 번 쪼개질 전역 메모리 트랜잭션 횟수를 단 한 번의 대형 버스트 송신으로 압축 단축 |
| 한 스레드가 레지스터를 너무 많이 처먹어, 남은 워프가 들어오지 못하는 심각한 코어 **점유율** 하락 | 커널 컴파일 시 블록당 스레드 수 및 공유 메모리 락업 사용량을 핀셋처럼 깎아내는 미세 조정 | 스트리밍 멀티프로세서 내 상주 워프 수를 폭발적으로 늘려 강력한 교체 **지연 은닉** 성능 강화 |
| 컴퓨터 메인보드와 그래픽 카드 사이의 좁은 톨게이트를 넘나드는 반복적인 데이터 송수신 지연 병목 | 두 개의 함수를 하나로 합치는 **커널 융합** 및 비디오 스트림 겹치기 기반 **비동기 전송** 야바위 적용 | 느려터진 PCIe 버스를 타고 오가는 메인 메모리 입출력 오버헤드를 연산 시간 뒤로 완벽 은닉 |

#### 한줄 요약

- 구조체(SoA)로 묶어 병합 접근을 유도하고, 조건문을 풀어 레인 낭비를 막으며, 레지스터 다이어트로 점유율을 끌어올려 무한 지연 은닉을 달성해야 그래픽 카드의 뽕을 뽑을 수 있다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실행 장치 아키텍처 선택 기준(Execution Engine Selection Criteria)**: 대상 소프트웨어의 병렬성 형태(데이터냐 작업이냐), 분기문의 꼬임 정도, 메모리 액세스의 규칙성을 잔인하게 뜯어보고 CPU, GPU, ASIC 중 누구에게 던져줄지 결정하는 최고위급 심판 잣대이다.

</details>

- **실행 장치 아키텍처 선택 기준**에 따라, 무식하게 방대한 대규모 데이터의 반복 병렬 및 메모리 접근 규칙성이 완벽한 환경은 한 치의 고민 없이 **단일 명령 다중 스레드 그래픽 장치(GPU SIMT)** 선정

#### 한줄 요약

- 수백만 픽셀이나 딥러닝 텐서처럼 조건문 없이 닥치고 똑같은 덧셈 곱셈만 죽어라 반복해야 하는 거대한 노가다판이라면 오직 그래픽 처리 장치만이 유일한 정답이다.
