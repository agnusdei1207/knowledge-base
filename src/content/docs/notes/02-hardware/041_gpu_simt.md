## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: 수많은 독립 스레드들을 워프(Warp: 32개 스레드) 단위로 묶어 단일 명령어 스트림으로 동시 병렬 실행하는 GPU 하드웨어 실행 모델.
- **GPU(Graphics Processing Unit)**: 수천 개의 소형 고효율 연산 코어와 초고대역폭 메모리(HBM/GDDR)를 집적하여 대규모 데이터 병렬성을 초고속 처리하는 프로세서.

</details>

- 정의/개념: 독립 스레드를 32개 단위의 워프(Warp)로 묶어 단일 명령어 스트림으로 락스텝(Lock-step) 병렬 실행하는 **GPU 하드웨어 실행 아키텍처**
- 배경/필요성: CPU의 복잡한 제어 논리(분기 예측, 비순차 실행) 한계 극복 및 수만 개 대규모 데이터 병렬성(Data Parallelism) 처리를 위한 연산 코어 고집적과 테라바이트급 대역폭 확보

#### 한줄 요약
- SIMT는 스레드별 독립 제어의 유연성과 SIMD의 대규모 하드웨어 병렬 실행 효율을 동시에 달성하는 GPU 핵심 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: SM 내부에서 단일 명령어로 함께 스케줄링되어 락스텝(Lock-step)으로 동시 실행되는 32개 스레드의 하드웨어 실행 단위.
- **지연시간 은닉(Latency Hiding)**: 한 워프가 DRAM 메모리 접근으로 대기할 때, 연산 준비가 완료된 다른 상주 워프로 즉시 스위칭하여 파이프라인 유휴를 없애는 기법.
- **분기 발산(Branch Divergence)**: 워프 내 스레드들이 조건문(if-else)에 따라 서로 다른 분기 경로를 탈 때, 경로별로 순차 직렬 실행되어 성능이 저하되는 현상.

</details>

- 32개 스레드가 단일 명령어 디코더를 공유하여 실리콘 면적당 **연산 코어(ALU) 집적도 극대화**
- 대용량 온칩 레지스터 파일에 수천 스레드의 실행 문맥을 상주시켜 제로 사이클 **지연시간 은닉(Latency Hiding)** 달성
- 워프 내 스레드들이 조건 분기에 따라 다른 경로를 실행할 때 액티브 마스크를 통한 **분기 발산(Branch Divergence) 직렬화** 수반

#### 한줄 요약
- 워프 공유 실행으로 제어 면적을 줄이고, 대용량 레지스터를 통한 지연 은닉으로 메모리 대기를 무력화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스트리밍 멀티프로세서(Streaming Multiprocessor, SM)**: 워프 스케줄러, 레지스터 파일, CUDA 코어, 텐서 코어, 공유 메모리를 통합 내장한 GPU의 핵심 독립 연산 유닛.
- **공유 메모리(Shared Memory / L1 Data Cache)**: 동일 스레드 블록 내 스레드들이 프로그래머 제어 하에 1~2사이클로 데이터를 초고속 공유하는 온칩 SRAM.

</details>

```text
+-------------------------------------------------------------+
|             스트리밍 멀티프로세서 어레이 (SM Array)          |
|  +-------------------------------------------------------+  |
|  |             단일 스트리밍 멀티프로세서 (SM)           |  |
|  |  +-------------------------------------------------+  |  |
|  |  |   워프 스케줄러 (Warp Scheduler) & 디스패치 유닛|  |  |
|  |  +-------------------------------------------------+  |  |
|  |                           |                           |  |
|  |                           v 32스레드 락스텝 명령어 발행|  |
|  |  +-------------------------------------------------+  |  |
|  |  |        초대용량 온칩 레지스터 파일 (64K~128K Regs)  |  |
|  |  +-------------------------------------------------+  |  |
|  |                           | 피연산자 공급             |  |
|  |                           v                           |  |
|  |  +-------------------------------------------------+  |  |
|  |  | 실행 코어군: 128개 CUDA 코어 & 4개 Tensor 코어  |  |  |
|  |  +-------------------------------------------------+  |  |
|  |                           |                           |  |
|  |  +-------------------------------------------------+  |  |
|  |  |   공유 메모리 (Shared Memory) / L1 데이터 캐시  |  |  |
|  |  +-------------------------------------------------+  |  |
|  |  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
                               |
                               v 온칩 고속 크로스바 인터커넥트
+-------------------------------------------------------------+
|               공유 L2 캐시 및 HBM3E 메모리 서브시스템        |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표는 워프 스케줄러의 단일 명령어 발행, 레지스터 파일의 피연산자 공급, CUDA/Tensor 코어 실행, 공유 메모리 및 L2/HBM 데이터 교환 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| 워프 스케줄러 | 연산 준비된 워프를 선별하여 실행 코어로 **단일 명령어를 제로 사이클 디스패치** |
| 온칩 레지스터 파일 | 수천 개 스레드의 문맥을 하드웨어에 상주시켜 **문맥 교환 오버헤드 원천 제거** |
| 실행 코어군 (CUDA/Tensor) | 단일 워프 내 32개 스레드의 SIMD 산술 연산 및 **행렬 곱셈(MMA) 병렬 실행** |
| 공유 메모리 (L1 Cache) | 동일 스레드 블록 내 스레드 간 **1사이클 초저지연 데이터 교환 및 타일링 지원** |

#### 한줄 요약
- 레지스터 파일이 수많은 스레드의 문맥을 상주시켜 실행 대상을 바꿀 때 문맥을 저장하고 복원하는 비용 자체를 없애고, 공유 메모리는 블록 안에서 오가는 데이터를 SM 내부에서 받아 내 L2와 HBM 왕복을 대신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **액티브 마스크(Active Mask)**: 분기 발산 발생 시 현재 실행 중인 분기 경로에 해당하는 스레드만 1로 인에이블하고 나머지는 일시 비활성화하는 하드웨어 마스크.

</details>

```text
+-------------------------------------------------------------+
|               호스트 CPU의 GPU 커널 함수 런칭                |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       1. 그리드/스레드 블록의 스트리밍 멀티프로세서(SM) 할당 |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       2. 스레드 블록 내 32개 스레드 단위의 워프(Warp) 분할  |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       3. 워프 스케줄러의 단일 명령어 동시 발행 (Issue)      |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     4. 조건 분기 일치 판정    |
               +-------------------------------+
                      |                 |
             [스레드 조건 일치]         | [분기 발산 발생 (if-else)]
                      |                 v
                      | +-------------------------------+
                      | | 액티브 마스크 설정            |
                      | | 참/거짓 경로 순차 직렬 실행   |
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 32개 코어 100% 동시 가동|             |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
|       5. DRAM 메모리 접근 시 대기 워프로 즉각 전환(은닉)     |
+-------------------------------------------------------------+
```

분기 결과: 워프 내 모든 스레드의 **조건 경로가 일치**하면 32개 연산기가 100% 동시 가동되나, **분기 발산** 발생 시 액티브 마스크에 의해 각 경로가 순차 직렬 실행되어 실행 시간이 배가됨

**동작 원리**

1. **스레드 블록 스케줄링**: 하드웨어 기가스레드 엔진(GigaThread Engine)이 그리드 내 스레드 블록들을 가용 자원이 있는 SM으로 디스패치
2. **32스레드 워프 분할**: SM이 수신된 블록의 스레드들을 32개씩 묶어 고유한 워프 ID를 부여하고 온칩 레지스터 공간 할당
3. **단일 명령 동시 발행**: 워프 스케줄러가 명령어 큐에서 피연산자가 준비된 활성 워프를 선택하여 32개 연산 유닛에 동일한 단일 명령어 발행
4. **액티브 마스크 직렬 분기**: if-else 분기문 발생 시 하드웨어 액티브 마스크가 참인 스레드만 활성화하여 먼저 실행한 후, 거짓인 스레드를 순차 실행하여 동기화
5. **제로 사이클 지연시간 은닉**: 현재 실행 워프가 DRAM 메모리 로드 요청으로 스톨되면, 스케줄러가 대기 없이 다른 준비된 워프로 즉시 전환하여 코어 연속 가동

#### 한줄 요약
- 워프 하나가 명령 인출과 발행을 32스레드분 공유해 제어 비용을 줄이는 대신, 분기가 발산하면 액티브 마스크로 경로를 나눠 순차 실행하는 시간 손실을 감수한다.

## Ⅴ. 종류 및 비교

| 병렬 처리 아키텍처 | SIMT (Single Instruction, Multiple Threads) | SIMD (Single Instruction, Multiple Data) | MIMD (Multiple Instruction, Multiple Data) |
|:---|:---|:---|:---|
| 적용 기준 | 수만 개 이상의 대규모 데이터 병렬 처리 및 GPU 가속 시 | CPU 벡터 레지스터 기반 규칙적 스트리밍 데이터 연산 시 | 코어별 독립 제어 흐름과 이기종 태스크 동시 병렬 실행 시 |
| 핵심 특징 | **워프 기반 단일 명령 공유** 및 스레드별 독립 제어 흐름 | 단일 프로세서 내 **초광폭 벡터 레지스터(AVX 등)** 직접 연산 | 독립적인 **다중 CPU 코어**가 서로 다른 명령어 스트림 실행 |
| 한계 | 분기 발산 발생 시 실행 직렬화 및 불규칙 메모리 접근 오버헤드 | 명시적 컴파일러 벡터화 의존 및 엄격한 데이터 정렬 요구 | 코어당 명령어 디코더 및 캐시 중복에 따른 **면적 오버헤드** |

#### 한줄 요약
- SIMD는 단일 벡터 레지스터에 종속되고 MIMD는 코어 확장이 제한적인 반면, SIMT는 수만 스레드의 대규모 데이터 병렬성을 완벽히 처리한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 병합(Memory Coalescing)**: 워프 내 32개 스레드의 연속 메모리 접근을 단 1회의 128바이트 DRAM 트랜잭션으로 결합하는 최적화.
- **뱅크 충돌(Bank Conflict)**: 공유 메모리의 동일 뱅크에 서로 다른 주소 접근이 동시 발생하여 접근이 직렬화되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워프 내 스레드 간 분기 불일치로 인한 분기 발산 | 데이터 정렬 및 **워프 특화(Warp-Specialized)** 커널 분할 | 분기 직렬화 제거 및 연산 코어 가동률 95% 이상 유지 |
| 불규칙한 비연속 메모리 스트라이드로 인한 대역폭 낭비 | 데이터 구조를 구조체 배열(AoS)에서 **배열 구조체(SoA)**로 변환 | **메모리 병합**으로 DRAM 트랜잭션 80% 절감 |
| 스레드당 과도한 레지스터 사용으로 인한 SM 점유율 하락 | 컴파일러 maxrregcount 지정 및 **공유 메모리 오프로딩** | SM당 상주 워프 수 극대화 및 지연시간 은닉 달성 |
| 공유 메모리 접근 시 뱅크 충돌 발생 | 공유 메모리 2차원 배열 열 **패딩(Padding)** 삽입 | 동시 접근 직렬화 해소 및 1사이클 접근 보장 |

#### 한줄 요약
- 실무에서는 메모리 병합(Coalescing), 워프 특화 분기 제거, 공유 메모리 패딩을 통해 GPU 대역폭과 점유율을 극대화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **TMA(Tensor Memory Accelerator)**: 비동기적으로 글로벌 메모리와 공유 메모리 간에 다차원 텐서를 레지스터 개입 없이 고속 복사하는 하드웨어 가속기.
- **워프 셔플(Warp Shuffle)**: 공유 메모리를 거치지 않고 워프 내 32개 스레드 간에 레지스터 데이터를 1사이클 내에 직접 교환하는 하드웨어 명령어.

</details>

대규모 데이터 병렬 연산의 제어 오버헤드를 극소화하고 스레드 단위의 유연성을 제공하는 현대 AI 및 고성능 컴퓨팅의 핵심 실행 모델이며, 텐서 코어와 TMA(Tensor Memory Accelerator) 및 CXL 메모리 패브릭과의 유기적 결합을 통한 초거대 AI 가속 진화.

#### 한줄 요약
- SIMT는 현대 AI와 고성능 컴퓨팅의 표준 실행 모델이며, 데이터 레이아웃 최적화와 텐서 코어 활용을 통해 압도적 처리량을 완성한다.
