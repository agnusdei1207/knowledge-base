## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **GPU(Graphics Processing Unit)**: 수천 개의 경량 산술 연산 코어로 대규모 데이터 병렬성(Data-Level Parallelism)을 처리하는 고처리량 가속기.
- **SIMT(Single Instruction Multiple Threads)**: 단일 명령어를 32개 스레드로 구성된 워프(Warp) 단위로 브로드캐스트하여 각 스레드가 서로 다른 데이터(SIMD)와 독자적인 레지스터 상태(MIMD 장점)를 갖게 하는 실행 모델.
- **Streaming Multiprocessor(SM)**: 워프 스케줄러, 레지스터 파일, 산술 연산기(ALU/Tensor Core), 공유 메모리(Shared Memory)를 통합한 GPU의 독립 연산 블록.

</details>

- 정의/개념: Streaming Multiprocessor(SM) 내부의 32개 스레드(Warp)가 단일 명령어를 서로 다른 독립 데이터에 병렬 실행하는 GPU 핵심 하드웨어 실행 모델
- 배경/필요성: CPU의 복잡한 분기 예측 및 아웃오브오더 제어 오버헤드를 배제하고, **대규모 스레드 병렬성(Data-Level Parallelism)과 지연 은닉(Latency Hiding)을 통해 극단적인 연산 처리량(Throughput) 확보**

#### 한줄 요약

- 단일 명령어로 32개 스레드(Warp)를 병렬 실행하여 **극단적 연산 처리량과 지연 은닉 달성**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Warp(워프)**: NVIDIA GPU에서 SIMT 실행의 기본 단위가 되는 32개 스레드 묶음 (AMD는 64개 Wavefront).
- **Latency Hiding(지연 은닉)**: 특정 워프가 수백 클록의 메모리 로드를 대기하는 동안, 준비된 다른 워프로 즉시 무비용 문맥 교환하여 연산 유닛 유휴를 방지하는 기법.
- **Coalesced Access(병합 접근)**: 워프 내 32개 스레드가 요청하는 연속 메모리 주소를 단 1~2회의 대형 캐시 라인(128바이트) 트랜잭션으로 통합 전송하는 기법.
- **Occupancy(점유율)**: SM이 수용할 수 있는 최대 워프 수 대비 현재 활성화된 워프 수의 비율.

</details>

- 메모리 로드 지연을 수천 개의 활성 스레드 간 초고속 제로 오버헤드 전환으로 상쇄하는 **지연 은닉(Latency Hiding)** 달성
- 32개 스레드 간 조건 분기(`if-else`) 발생 시 **Active Mask**를 적용하여 경로를 순차 실행하는 **분기 발산(Branch Divergence)** 수반
- 인접 스레드의 연속 주소 요청을 1회 트랜잭션으로 묶는 **Coalesced Access(병합 접근)**를 통해 메모리 대역폭 활용 극대화

#### 한줄 요약

- **Warp 단위 스케줄링·초고속 지연 은닉(Latency Hiding)·Coalesced 병합 메모리 접근**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Warp Scheduler**: 매 사이클마다 연산 준비가 완료된 활성 워프를 선별하여 실행 유닛으로 디스패치하는 스케줄러.
- **Shared Memory**: 동일 스레드 블록 내 스레드들이 외부 VRAM 접근 없이 초저지연(수 사이클)으로 데이터를 공유하는 온칩 SRAM.

</details>

```text
[ GPU Streaming Multiprocessor (SM) 내부 구조도 ]
┌─────────────────────────────────────────────────────────────┐
│ 명령어 캐시 (Instruction Cache)                             │
│  └─ 워프 스케줄러 & 디스패치 유닛 (Warp Schedulers)          │
└──────────────────────────────┬──────────────────────────────┘
                               │ (단일 명령 브로드캐스트)
┌──────────────────────────────┴──────────────────────────────┐
│ 대용량 레지스터 파일 (Register File : 64K~256KB SRAM)       │
│  ├─ Thread 0 ~ Thread 31 개별 레지스터 상태 보존            │
│  └─ Zero-Overhead Context Switching 지원                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 연산 파이프라인 (Execution Units)                           │
│  ├─ FP32 / INT32 코어 (수백 개 ALU)                          │
│  ├─ Tensor Core (FP16/BF16/FP8/INT4 행렬 가속 엔진)         │
│  └─ 온칩 공유 메모리 / L1 데이터 캐시 (Shared Memory SRAM)  │
└──────────────────────────────┬──────────────────────────────┘
                               │
═══════════════════════════════╧═══════════════════════════════ (온칩 NoC / L2 캐시)
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 초고대역폭 전역 메모리 (HBM3 / GDDR6 VRAM)                  │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 워프 스케줄러, 레지스터 파일, ALU/텐서 코어, 공유 메모리 및 L2/전역 메모리 간의 GPU SM 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 워프 스케줄러 | 연산 대기 중인 **워프**들 사이에서 준비된 놈을 재빨리 골라내어 인스트럭션 제어 파이프라인으로 디스패치 |
| 연산 및 로드 스토어 유닛 | 무수히 깔린 실수/정수 연산기로 덧셈과 곱셈을 쳐내고, 메모리 로드 및 스토어 트랜잭션을 물리적 수행 |
| 레지스터 및 공유 메모리 | 각 스레드의 찰나의 실행 상태를 수만 개의 레지스터에 보관하고, 블록 내 스레드 간 고속 텐서 데이터 공유 |
| 레벨 2 캐시 및 전역 메모리 | 모든 **스트리밍 멀티프로세서** 군단 간의 데이터 일관성 교통정리 제공 및 최종 거대 텐서 데이터 영구 저장 |

#### 한줄 요약

- **워프 스케줄러·대용량 레지스터 파일·ALU/Tensor 코어·공유 메모리(SRAM)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Branch Divergence**: 워프 내 스레드들이 서로 다른 실행 경로로 갈라져, 한쪽 경로가 실행되는 동안 다른 쪽 스레드가 마스킹(비활성화)되어 처리량이 저하되는 현상.

</details>

```text
[ GPU 커널 실행 및 SIMT 스케줄링 흐름 ]
                         │
                         ▼
   [ 1. 그리드/블록 단위로 스레드를 SM에 하드웨어 매핑 ]
                         │
                         ▼
   [ 2. 워프 스케줄러가 준비된 활성 워프 선택 및 명령어 발행 ]
                         │
                         ▼
   [ 3. 32개 스레드의 인접 주소를 Coalesced Memory로 일괄 인출 ]
                         │
        [ if-else 조건문 분기 발생 여부 ]
                         │
        ┌────────────────┴────────────────┐
        ▼ [동일 경로]                     ▼ [분기 발산 발생]
   [ 4-A. 32개 스레드 동시 연산 ]     [ 4-B. Active Mask로 경로 순차 직렬화 ]
        │                                 │
        └────────────────┬────────────────┘
                         ▼
   [ 5. 연산 중 메모리 대기 발생 시 타 워프로 즉시 전환 (지연 은닉) ]
                         │
                         ▼
   [ 6. 블록 내 모든 워프 완료 시 자원 반환 및 다음 블록 스케줄링 ]
```

**동작 원리**

1. **블록 할당**: 하드웨어 디스패처가 가용 레지스터와 공유 메모리를 확인하여 Thread Block을 SM에 할당
2. **워프 스케줄링**: 워프 스케줄러가 준비된 워프를 선택하여 단일 사이클에 32개 스레드로 명령 전달
3. **병합 인출**: 32개 스레드의 메모리 요청을 검사하여 연속된 주소인 경우 단일 캐시 라인 트랜잭션으로 인출
4. **분기 처리**: 워프 내부 분기 발생 시 Active Mask를 토글하며 `if`와 `else` 블록을 순차 실행
5. **지연 은닉**: 긴 메모리 대기(Long Latency)가 발생하면 즉시 다른 준비된 워프로 실행 전환

#### 한줄 요약

- Thread Block SM 배치 $\to$ **Warp 스케줄링 $\to$ Coalesced 메모리 인출 $\to$ 분기 마스크 실행**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIMT vs SIMD vs MIMD**:
  - SIMT: 스레드 단위 프로그래밍, 32스레드 락스텝 하드웨어 워프 실행 (GPU)
  - SIMD: 단일 스레드가 고정 폭 벡터 레지스터 일괄 연산 (AVX-512)
  - MIMD: 다중 독립 코어가 각자의 PC와 스레드를 비동기 실행 (CPU Multi-Core)

</details>

| 비교 항목 | SIMT 모델 (GPU) | SIMD 모델 (CPU Vector) | MIMD / 멀티스레딩 (CPU Multi-Core) |
|:---|:---|:---|:---|
| 실행 제어 및 단위 | 스레드 단위 프로그래밍, 32스레드 Warp 일괄 발행 | 고정 크기 벡터 레지스터(AVX-512) 단일 명령어 실행 | 코어별 독립적 명령어 스트림(PC) 비동기 실행 |
| 분기 처리 메커니즘 | Active Mask 기반 분기 직렬화 (Branch Divergence) | 마스크 레지스터(Predication) 벡터 조건부 연산 | 하드웨어 분기 예측기(Branch Predictor) 및 OoO |
| 한계 및 오버헤드 | 분기 발산 시 성능 저하, 비병합 접근 시 대역폭 낭비 | 엄격한 데이터 연속 정렬 및 컴파일러 벡터화 의존 | 코어 수 확장 한계 및 무거운 문맥 교환 오버헤드 |

#### 한줄 요약

- 대규모 병렬은 **GPU SIMT**, 소량 벡터는 **CPU SIMD**, 복잡한 제어는 **CPU Multi-Core**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SoA(Structure of Arrays)**: `Array of Structures(AoS)` 대신 구조체 필드별로 배열을 분리하여 스레드들이 연속 주소에 접근하도록 하는 GPU 친화적 메모리 레이아웃.
- **Kernel Fusion**: 복수의 연속된 GPU 커널을 하나의 커널로 합쳐 중간 결과를 VRAM에 쓰지 않고 레지스터/공유 메모리에서 즉시 소비하는 최적화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지독하게 꼬인 조건문(if-else)으로 인한 **분기 발산** 발생 시 반쪽짜리 연산 코어 성능 저하 타격 | 코드 레벨에서 동일 분기 조건끼리 데이터를 미리 재배치 정렬하여 **레인 활용률** 한계 돌파 최적화 | 놀고먹는 비활성 레인 방치 시간을 박멸하고 스레드 단위의 연산 효율 극한 증대 |
| 스레드들이 뿔뿔이 흩어진 주소를 요청하는 치명적인 **비병합 접근** 감지 및 메모리 대역폭 폭발 | 데이터를 구조체 배열(SoA) 형식으로 뜯어고쳐 강제 연속 **병합 접근**이 가능하도록 메모리 맵 재배치 | 수백 번 쪼개질 전역 메모리 트랜잭션 횟수를 단 한 번의 대형 버스트 송신으로 압축 단축 |
| 한 스레드가 레지스터를 너무 많이 처먹어, 남은 워프가 들어오지 못하는 심각한 코어 **점유율** 하락 | 커널 컴파일 시 블록당 스레드 수 및 공유 메모리 락업 사용량을 핀셋처럼 깎아내는 미세 조정 | 스트리밍 멀티프로세서 내 상주 워프 수를 폭발적으로 늘려 강력한 교체 **지연 은닉** 성능 강화 |
| 컴퓨터 메인보드와 그래픽 카드 사이의 좁은 톨게이트를 넘나드는 반복적인 데이터 송수신 지연 병목 | 두 개의 함수를 하나로 합치는 **커널 융합** 및 비디오 스트림 겹치기 기반 **비동기 전송** 야바위 적용 | 느려터진 PCIe 버스를 타고 오가는 메인 메모리 입출력 오버헤드를 연산 시간 뒤로 완벽 은닉 |

#### 한줄 요약

- **분기 발산 최소화·SoA 기반 Coalesced Access·점유율(Occupancy) 최적화·커널 퓨전**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **GPU Tensor Core / Transformer Engine**: SIMT 코어 위에 혼합 정밀도(FP8, FP16, INT8) 행렬 연산 전용 하드웨어를 직접 통합하여 생성형 AI 처리량을 수십 배 가속화.

</details>

- 딥러닝 텐서 연산 및 그래픽 렌더링 환경에서 **SIMT 기반 GPU 및 Tensor Core 하드웨어 가속 표준 채택**

#### 한줄 요약
