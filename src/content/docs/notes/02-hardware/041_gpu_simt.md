## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **그래픽 처리 장치(Graphics Processing Unit, GPU)**: 다수의 스레드로 같은 형태의 데이터 병렬 연산을 높은 처리량으로 수행하는 프로세서이다.
- **단일 명령 다중 스레드(Single Instruction, Multiple Threads, SIMT)**: 하나의 명령을 실행 묶음의 활성 스레드들에 공통으로 발행하는 GPU 실행 모델이다.
- **스트리밍 멀티프로세서(Streaming Multiprocessor, SM)**: 워프 스케줄링과 연산 및 온칩 메모리 관리를 담당하는 GPU 실행 단위이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 복잡한 제어와 소수 스레드의 짧은 지연 실행에 강한 범용 프로세서이다.

</details>

- 정의/개념: GPU의 SM이 다수 스레드를 워프 단위로 묶어 공통 명령을 발행하는 **SIMT** 실행 구조이다.
- 배경/필요성: CPU의 소수 복잡 코어만으로는 많은 데이터 원소의 동일 연산을 동시에 처리하기 어렵다.

#### 한줄 요약

- GPU는 스레드를 워프로 묶어 같은 명령을 발행하고 준비된 워프를 교대 실행해 대규모 동일 연산의 처리량을 높인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **워프(Warp)**: NVIDIA GPU가 하나의 명령으로 함께 실행하는 32개 스레드의 묶음이다.
- **지연 은닉(Latency Hiding)**: 한 워프가 메모리를 기다리는 동안 준비된 다른 워프를 실행해 대기 시간을 숨기는 기법이다.
- **활성 마스크(Active Mask)**: 워프에서 현재 명령을 실제로 실행할 스레드만 표시하는 비트 집합이다.
- **병합 접근(Coalesced Access)**: 인접한 스레드의 연속 주소 요청을 적은 수의 메모리 트랜잭션으로 합치는 접근 방식이다.
- **점유율(Occupancy)**: SM에 실제로 상주한 워프 수를 하드웨어가 허용하는 최대 상주 워프 수로 나눈 비율이다.

</details>

- 메모리 대기 시간을 숨기는 **지연 은닉**이 핵심이다.
- 분기 경로를 순차 실행하는 **활성 마스크**가 핵심이다.
- 메모리 처리량을 좌우하는 **병합 접근·점유율**이 핵심이다.

#### 한줄 요약

- 워프 전환은 메모리 대기 시간을 다른 워프의 실행으로 숨기고, 병합 접근은 전역 메모리 트랜잭션 수를 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **워프 스케줄러(Warp Scheduler)**: 실행 준비가 된 워프를 선택하고 공통 명령을 연산 유닛에 발행하는 하드웨어이다.
- **공유 메모리(Shared Memory)**: 하나의 스레드 블록이 데이터를 빠르게 교환하고 재사용하는 온칩 메모리이다.
- **전역 메모리(Global Memory)**: 모든 스레드 블록이 접근할 수 있지만 온칩 메모리보다 지연이 큰 그래픽 처리 장치(Graphics Processing Unit, GPU) 메모리이다.
- **2차 캐시(Level 2 Cache, L2 Cache)**: 모든 스트리밍 멀티프로세서가 공유하는 장치 캐시 계층이다.

</details>

```text
                      [워프 스케줄러]
                              |
                              |
[레지스터•공유 메모리] -- [연산•로드/저장 유닛] -- [L2•전역 메모리]
```

선의 의미: 연산•로드/저장 유닛을 중심으로 워프 제어와 온칩•장치 메모리 계층이 결합된 정적 SM 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 워프 스케줄러 | 실행 워프 선택•명령 발행 |
| 연산•로드/저장 유닛 | 산술•분기•주소 접근 |
| 레지스터•공유 메모리 | 상태•재사용 데이터 보관 |
| L2•전역 메모리 | 공유 캐시•장치 데이터 제공 |

#### 한줄 요약

- 스케줄러가 준비된 워프를 연산 유닛과 메모리 계층에 번갈아 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **블록 디스패처(Block Dispatcher)**: 커널의 스레드 블록을 자원이 충분한 스트리밍 멀티프로세서(Streaming Multiprocessor, SM)에 배치하는 하드웨어이다.
- **스레드 블록(Thread Block)**: 같은 SM에 함께 배치되어 공유 메모리와 동기화를 사용하는 스레드 묶음이다.
- **분기 발산(Branch Divergence)**: 한 워프의 스레드들이 서로 다른 분기 경로를 선택해 경로별로 순차 실행되는 현상이다.
- **SM 배치·자원 할당**: 블록에 필요한 레지스터와 공유 메모리를 확보해 상주 워프를 만드는 단계이다.
- **준비 워프 명령 발행**: 실행 가능한 워프를 선택해 활성 스레드에 공통 명령을 내리는 단계이다.
- **메모리 접근 병합**: 워프의 연속 주소 요청을 적은 수의 전역 메모리 트랜잭션으로 합치는 단계이다.
- **분기 활성 마스크 실행**: 분기 경로별 활성 스레드만 선택해 각 경로를 순서대로 실행하는 단계이다.
- **블록 자원 해제**: 블록 완료 뒤 레지스터와 공유 메모리를 다음 블록에 반환하는 단계이다.

</details>

```text
                    [커널 스레드 블록]
                              |
                   1. SM 배치•자원 할당
                              |
                      [준비 워프 선택]
                              |
          +---------------------------------------+
          | 반복: 블록의 모든 워프 완료 전       |
          | 2. 활성 워프 명령 발행               |
          |              |                        |
          |          [명령 유형]                  |
          |       /       |        \              |
          |    [산술]   [메모리]   [분기]         |
          |      |         |         |             |
          |   [실행]  3. 병합 접근  4. 활성 마스크 실행 |
          |              |                        |
          |        [다음 준비 워프 선택]          |
          +---------------------------------------+
                              |
                   5. 블록 자원 해제
```

### 동작 원리

1. **SM 배치·자원 할당**: **블록 디스패처**가 블록의 스레드 수에 맞춰 레지스터와 공유 메모리를 확보하고 상주 워프를 생성한다.
2. **준비 워프 명령 발행**: 워프 스케줄러가 실행 가능한 워프를 선택해 활성 스레드에 공통 명령을 발행한다.
3. **메모리 접근 병합**: 워프의 연속 주소 요청을 가능한 적은 전역 메모리 트랜잭션으로 결합한다.
4. **분기 활성 마스크 실행**: 워프 내부 경로가 갈리면 경로별 활성 마스크를 적용해 각 분기를 순차 실행한다.
5. **블록 자원 해제**: 블록의 모든 워프가 끝나면 레지스터·공유 메모리를 반환해 다음 블록 배치를 허용한다.

#### 한줄 요약

- 준비된 워프를 교대 실행해 메모리 지연을 숨기고, 분기 발산은 경로별 활성 마스크로 순차 처리한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **단일 명령 다중 데이터(Single Instruction, Multiple Data, SIMD)**: 하나의 벡터 명령을 여러 데이터 레인에 동시에 적용하는 실행 방식이다.
- **벡터 레인(Vector Lane)**: SIMD 명령에서 서로 다른 데이터 원소를 병렬로 처리하는 연산 통로이다.
- **중앙 처리 장치 스레드(Central Processing Unit Thread, CPU 스레드)**: 독립적인 명령 흐름과 실행 상태를 가지며 복잡한 제어를 수행하는 실행 단위이다.
- **비병합 접근**: 인접 스레드의 주소가 흩어져 여러 메모리 트랜잭션이 필요한 접근이다.

</details>

| 병렬 실행 방식 | GPU SIMT | CPU SIMD | CPU 스레드 |
|:---|:---|:---|:---|
| 적용 기준 | 대규모 동일 연산 | 벡터화 가능한 반복문 | 복잡한 분기•낮은 병렬성 |
| 핵심 특징 | **SIMT** 워프 | **SIMD·벡터 레인** | 독립 **CPU 스레드** |
| 한계 | **분기 발산·비병합 접근** | 벡터 폭 미활용 | 문맥 전환•동기화 비용 |

> 요약: 대규모 동일 연산은 SIMT, 복잡한 분기는 CPU가 적합하다.

#### 한줄 요약

- 대규모 독립 데이터의 동일 연산은 GPU SIMT, 벡터화 가능한 반복문은 CPU SIMD, 복잡한 독립 제어 흐름은 CPU 스레드가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **레인 활용률(Lane Utilization)**: 워프의 전체 실행 레인 가운데 활성 스레드가 유효한 연산을 수행하는 비율이다.
- **커널 융합(Kernel Fusion)**: 연속된 커널을 하나로 결합해 실행 시작 비용과 중간 데이터의 전역 메모리 왕복을 줄이는 최적화 기법이다.
- **비동기 전송(Asynchronous Transfer)**: 계산과 데이터 이동을 겹치도록 완료를 기다리지 않고 전송을 시작하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 한 워프의 스레드가 다른 분기를 선택해 **분기 발산** | 같은 경로의 데이터를 묶고 **레인 활용률** 측정 | 비활성 레인 감소 |
| 인접 스레드가 떨어진 주소를 요청해 **비병합 접근** 발생 | 자료 구조와 인덱스를 **병합 접근**에 맞게 배치 | 메모리 트랜잭션 감소 |
| 블록당 레지스터·공유 메모리 사용이 커서 상주 워프 감소 | 블록 크기와 스레드당 자원량을 조정해 **점유율·지연 은닉** 비교 | 준비 워프 수 균형 |
| 실행 시간이 짧은 커널에서 시작·전송 비용이 연산 시간 지배 | **커널 융합·비동기 전송**으로 호출과 중간 데이터 왕복 축소 | 오버헤드 감소 |

> 영상 필터는 인접 화소를 같은 워프의 연속 스레드에 배치해 전역 메모리 요청을 병합한다.

#### 한줄 요약

- 영상 필터는 연속 화소를 같은 워프에 배치해 메모리 요청을 병합하고 분기 발산을 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **동일 연산(Data-parallel Operation)**: 많은 데이터 원소에 같은 계산 절차를 독립적으로 적용하는 연산이다.
- **복잡한 분기(Control-heavy Branching)**: 데이터마다 실행 경로가 자주 달라져 SIMT 레인 활용률을 낮추는 제어 흐름이다.
- **메모리 접근 규칙성(Memory Access Regularity)**: 인접 스레드가 연속된 주소를 일정한 형태로 요청하는 정도이다.
- **실행 장치 선택 기준**: 동일 연산·분기 복잡도·메모리 접근 규칙성으로 GPU와 CPU를 고르는 기준이다.

</details>

- **실행 장치 선택 기준**에 따라 **동일 연산**과 **메모리 접근 규칙성**이 높으면 **GPU**, **복잡한 분기**가 많으면 **CPU**를 선택한다.

#### 한줄 요약

- 동일 연산이 많고 스레드 주소를 병합할 수 있으면 GPU를, 데이터마다 복잡한 분기 경로를 실행하면 CPU를 선택한다.
