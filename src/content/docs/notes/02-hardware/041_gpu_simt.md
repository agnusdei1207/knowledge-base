## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: 수많은 독립 스레드를 워프(32개 스레드) 단위로 묶어 동일 명령어를 동시 병렬 실행하는 GPU 하드웨어 실행 모델.
- **GPU(Graphics Processing Unit)**: 수천 개의 소형 연산 코어와 초고대역폭 메모리를 집적하여 대규모 병렬 연산을 가속하는 프로세서.

</details>

- 정의/개념: 독립 스레드들을 **워프** 단위로 묶어 한 명령어로 동시에 실행하는 **SIMT** 하드웨어 모델
- 배경/필요성: 단일 제어 기반 소수 코어 구조로는 **대규모 텐서·그래픽 병렬 연산의 처리량 극대화 불가**

#### 한줄 요약
- SIMT는 스레드를 독립 실행처럼 보이게 하면서도 하드웨어적으로는 워프 단위로 묶어 한 명령어로 동시 처리하는 고성능 병렬 모델이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: SM 내부에서 동시에 스케줄링되어 한 명령어를 함께 실행하는 32개 스레드의 하드웨어 묶음 단위.
- **지연시간 은닉(Latency Hiding)**: 한 워프가 메모리를 기다릴 때 실행 가능한 다른 워프를 발행해 유휴 시간을 줄이는 기법.
- **분기 발산(Branch Divergence)**: 워프 내 스레드들이 if-else 조건에 따라 서로 다른 경로로 분기할 때 경로별로 순차 실행되어 성능이 저하되는 현상.

</details>

- 워프 단위 실행으로 명령어 인출·해독 회로를 32개 스레드가 공유
- **지연시간 은닉**을 통해 메모리를 기다리는 워프 대신 준비된 워프를 즉시 발행
- 조건 분기에서 **분기 발산** 발생 시 경로별 순차 실행으로 성능 저하

#### 한줄 요약
- GPU는 지연을 줄이는 대신 감추는 쪽을 택했으므로, 감출 다른 워프가 없으면 초고대역폭 메모리를 달아도 연산기가 멈춰 선다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SM(Streaming Multiprocessor)**: 워프 스케줄러, 레지스터 파일, 연산 코어, 공유 메모리를 갖춘 GPU의 핵심 연산 유닛.
- **공유 메모리(Shared Memory)**: 동일 스레드 블록 내 스레드들이 초고속으로 데이터를 공유할 수 있는 온칩 고속 SRAM.

</details>

```text
[GPU 연산 계층]
|-- SM (Streaming Multiprocessor)
|   |-- 워프 스케줄러·디스패치 유닛
|   |-- 대용량 레지스터 파일 (상주 워프 문맥 보관)
|   |-- 연산 코어 (FP32/INT32/텐서 코어)
|   `-- 공유 메모리·L1 데이터 캐시
`-- 칩 공유 계층
    |-- L2 캐시
    `-- 고대역폭 메모리 (HBM/GDDR)
```

선의 의미: 계층 및 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| **SM** | 스레드 블록 수용과 워프 스케줄링·병렬 연산 총괄 |
| 워프 스케줄러 | 매 클록마다 명령어 실행 준비가 완료된 워프를 선택해 실행 유닛에 디스패치 |
| 레지스터 파일 | 상주 워프 문맥을 통째로 보관해 문맥 전환 비용 제거 |
| CUDA·텐서 코어 | 부동소수점 연산 및 AI 딥러닝 고속 행렬 곱셈 누산(MMA) 수행 |
| **공유 메모리**·L1 캐시 | 블록 내 데이터 교환과 외부 메모리 접근 트래픽 완화 |

#### 한줄 요약
- 레지스터 파일이 비정상적으로 큰 이유는 워프 전환 비용을 없애기 위함이며, CPU가 문맥 교환에 쓰는 오버헤드를 GPU는 면적으로 해결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **액티브 마스크(Active Mask)**: 분기 발산 시 현재 분기 경로를 실행할 스레드만 1로 켜고 나머지는 끄는 하드웨어 제어 마스크.

</details>

```text
커널 실행 요청 (그리드·블록 구성)
        │
   블록을 SM에 배치 후 32스레드씩 워프 구성
        │
   발행 가능한 워프가 있는가?
   ┌────┴─────┐
  예           아니오
   │             │
동일 명령어 발행  연산 유닛 유휴 (은닉 실패)
   │
   워프 내 스레드가 같은 경로인가?
   ┌────┴─────┐
  예           아니오
   │             │
32스레드 동시   경로별로 나눠 순차 실행
실행            (미해당 스레드는 유휴)
   └────┬───────┘
        │
   메모리 대기 발생 시 다른 워프로 전환
```

#### 한줄 요약
- 액티브 마스크를 통해 분기를 처리하므로, 조건문이 갈리면 워프 내 스레드들이 순차 실행되어 연산 효율이 급감한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 단일 명령어로 여러 데이터 벡터 레지스터를 동시 처리하는 CPU 벡터 구조.
- **MIMD(Multiple Instructions, Multiple Data)**: 여러 독립 프로세서가 각각 서로 다른 명령어와 데이터를 처리하는 구조.

</details>

| 병렬 처리 아키텍처 | SIMT (GPU) | SIMD (CPU 벡터) | MIMD (멀티코어 CPU) | Systolic Array (TPU) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 대규모 데이터 병렬·AI/그래픽 | 정형 벡터 루프 연산 가속 | 복잡한 제어 흐름·다양한 태스크 | 고정 행렬 곱셈(GEMM) 전용 가속 |
| 핵심 특징 | 수천 개 스레드를 워프로 묶어 동시 실행 | 1개 명령어에 다중 데이터 벡터 레지스터 연산 | 각 코어가 독립 명령어 스트림 독립 실행 | 2차원 격자 셀로 데이터가 파이프라인 전파 |
| 한계 | 분기 발산 시 직렬화 패널티 발생 | 벡터 폭 제한 및 제어 유연성 부족 | 코어 수 확장 한계 및 높은 전력 소모 | 범용 연산 불가·고정된 연산 패턴 |

#### 한줄 요약
- 네 구조는 명령어 하나가 몇 개의 데이터를 책임지느냐로 나뉘며, 그 수가 클수록 처리량은 오르고 제어 흐름의 자유도는 줄어든다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 병합(Memory Coalescing)**: 워프 내 32개 스레드의 메모리 접근 주소가 연속적일 때 하나의 128바이트 트랜잭션으로 결합하는 기술.
- **뱅크 충돌(Bank Conflict)**: 공유 메모리의 동일 뱅크 내 서로 다른 주소를 워프 스레드들이 동시 접근할 때 직렬화되는 현상.
- **점유율(Occupancy)**: SM에 동시 상주할 수 있는 워프 수의 비율로, 낮으면 전환할 워프가 부족해 지연 은닉이 무너짐.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워프 내 if-else 조건문으로 인한 **분기 발산** | 데이터 정렬·커널 분리로 같은 워프의 실행 경로 통일 | 경로별 직렬 실행 비율 감소 |
| 비연속 메모리 접근으로 트랜잭션 수 증가 | **메모리 병합** 노린 구조체 배열(AoS)의 배열 구조체(SoA) 전환 | 필요한 메모리 트랜잭션 수 감소 |
| 스레드당 과도한 레지스터 사용으로 **점유율** 저하 | 컴파일러 maxrregcount 옵션 설정 및 변수 수명 최적화 | SM당 동시 상주 워프 수 증가 및 지연 은닉 강화 |
| 공유 메모리 동시 접근 시 **뱅크 충돌** | 패딩 적용으로 스레드별 접근 뱅크 분산 | 직렬화되는 공유 메모리 접근 지연 감소 |

#### 한줄 요약
- GPU 최적화는 알고리즘 튜닝보다 메모리 병합과 뱅크 충돌 방지 등 데이터 레이아웃 재배치가 핵심이다.

## Ⅶ. 결론

- 대규모 데이터 병렬성과 고대역폭이 요구되면 **SIMT** 기반 **GPU**를 선택하고, 분기 발산과 비연속 접근이 지배적인 태스크는 **CPU 병행** 처리 적용

#### 한줄 요약
- GPU 적합성은 단순 연산량이 아니라 스레드 간 실행 경로와 메모리 접근 패턴의 균일성에 의해 결정된다.
