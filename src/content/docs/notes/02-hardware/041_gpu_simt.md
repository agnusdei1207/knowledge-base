## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: 수많은 독립 스레드를 워프(32개 스레드) 단위로 묶어 동일 명령어를 동시 병렬 실행하는 GPU 하드웨어 실행 모델.
- **GPU(Graphics Processing Unit)**: 수천 개의 소형 연산 코어와 초고대역폭 메모리를 집적하여 대규모 병렬 연산을 가속하는 프로세서.

</details>

- 정의/개념: 다수의 스레드를 **워프(Warp)** 단위로 묶어 단일 명령어로 동시 실행하는 대규모 하드웨어 병렬 아키텍처
- 배경/필요성: 소수의 복잡한 CPU 코어로는 독립 데이터가 많은 텐서·그래픽 연산의 병렬성 활용 제한

#### 한줄 요약
- 스레드를 32개씩 워프로 묶어 하나의 명령어로 동시 실행하고, 메모리 대기 시간은 다른 워프로 채워 숨긴다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: SM 내부에서 동시에 스케줄링되어 한 명령어를 함께 실행하는 32개 스레드의 하드웨어 묶음 단위.
- **지연시간 은닉(Latency Hiding)**: 한 워프가 메모리를 기다릴 때 실행 가능한 다른 워프를 발행해 유휴 시간을 줄이는 기법.
- **분기 발산(Branch Divergence)**: 워프 내 스레드들이 if-else 조건에 따라 서로 다른 경로로 분기할 때 경로별로 순차 실행되어 성능이 저하되는 현상.

</details>

- **워프(Warp) 단위 실행**으로 단일 명령어 디코딩 공유 및 하드웨어 효율화
- **지연시간 은닉(Latency Hiding)** 으로 메모리 대기 시 타 워프 즉시 전환
- 조건문 분기 시 **분기 발산(Divergence)** 에 따른 직렬화 패널티 발생

#### 한줄 요약
- 하드웨어는 워프 단위로 일괄 처리하며, 대기 시간이 생기면 다른 워프로 즉시 전환해 쉬지 않고 연산한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SM(Streaming Multiprocessor)**: 워프 스케줄러, 레지스터 파일, 연산 코어, 공유 메모리를 갖춘 GPU의 핵심 연산 유닛.
- **공유 메모리(Shared Memory)**: 동일 스레드 블록 내 스레드들이 초고속으로 데이터를 공유할 수 있는 온칩 고속 SRAM.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 스트리밍 다중처리기 (Streaming Multiprocessor, SM)           │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 워프 스케줄러 (Warp Scheduler) & 디스패치 유닛 (Dispatch) │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │ (명령어 발행)                 │
│  ┌──────────────────────────┴────────────────────────────┐  │
│  │ 대용량 레지스터 파일 (Register File, 64K x 32bit)       │  │
│  └───────────┬───────────────────────────┬───────────────┘  │
│              │                           │                  │
│  ┌───────────────────────┐   ┌───────────────────────┐      │
│  │ FP32 / INT32 코어 (ALU)│   │ 텐서 코어 (Tensor Core)│      │
│  │ (32 스레드 병렬 실행) │   │ (MMA 행렬 곱셈 누산)  │      │
│  └───────────────────────┘   └───────────────────────┘      │
│              │                           │                  │
│  ┌───────────┴───────────────────────────┴───────────────┐  │
│  │ 공유 메모리 (Shared Memory) / L1 데이터 캐시          │  │
│  └──────────────────────────┬────────────────────────────┘  │
└─────────────────────────────┼───────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│ 칩 전체 공유 L2 캐시 및 고대역폭 메모리 (HBM3 / GDDR6X)      │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 스케줄러·레지스터·연산 코어·메모리 계층 사이의 정적 연결

| 구성요소 | 책임 |
|:---|:---|
| 스트리밍 다중처리기 (SM) | 다중 스레드 블록을 수용하여 워프 스케줄링 및 병렬 연산 총괄 |
| 워프 스케줄러 | 매 클록마다 명령어 실행 준비가 완료된 워프를 선택해 실행 유닛에 디스패치 |
| 대용량 레지스터 파일 | 상주 워프의 실행 문맥을 보관해 빠른 워프 전환 지원 |
| CUDA 코어 / 텐서 코어 | 범용 부동소수점 연산 및 AI 딥러닝 고속 행렬 곱셈(MMA) 수행 |
| 공유 메모리 / L1 캐시 | 스레드 블록 내 초고속 데이터 교환 및 글로벌 메모리 접근 트래픽 완화 |

#### 한줄 요약
- SM 내부의 워프 스케줄러, 레지스터 파일, 연산 코어, 공유 메모리가 고도로 밀결합되어 동작한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **액티브 마스크(Active Mask)**: 분기 발산 시 현재 분기 경로를 실행할 스레드만 1로 켜고 나머지는 끄는 실행 제어 마스크.

</details>

```text
호스트: 커널 실행 요청 (그리드·블록 구성)
      │
      ▼
1. 블록 배치
      │
      ▼
2. 워프 구성
      │
      ▼
3. 명령어 발행
      │
      ▼
4. 분기 처리
      │
      ▼
5. 지연 은닉
```

**동작 원리**

1. **블록 배치**: 호스트가 요청한 스레드 블록들을 SM의 하드웨어 자원에 맞춰 분배
2. **워프 구성**: 블록 내부의 연속된 32개 스레드를 워프로 묶어 스케줄러 큐에 등록
3. **명령어 발행**: 스케줄러가 의존성이 해결된 워프를 골라 32개 연산 유닛에 동일 명령어 디스패치
4. **분기 처리**: if-else 조건 분기 시 액티브 마스크를 이용해 true 스레드와 false 스레드를 순차 처리
5. **지연 은닉**: 워프가 글로벌 메모리 로드를 대기할 때 다른 활성 워프로 즉각 전환하여 연산기 풀가동

#### 한줄 요약
- 블록 배치 → 워프 구성 → 단일 명령 동시 발행 → 분기 마스킹 → 메모리 대기 시 타 워프 즉시 전환 순이다.

## Ⅴ. 종류 및 비교

| 병렬 처리 아키텍처 | SIMT (GPU) | SIMD (CPU 벡터) | MIMD (멀티코어 CPU) | Systolic Array (TPU) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 대규모 데이터 병렬·AI/그래픽 | 정형 벡터 루프 연산 가속 | 복잡한 제어 흐름·다양한 태스크 | 고정 행렬 곱셈(GEMM) 전용 가속 |
| 핵심 특징 | 수천 개 스레드를 워프로 묶어 동시 실행 | 1개 명령어에 다중 데이터 벡터 레지스터 연산 | 각 코어가 독립 명령어 스트림 독립 실행 | 2차원 격자 셀로 데이터가 파이프라인 전파 |
| 한계 | 분기 발산 시 직렬화 패널티 발생 | 벡터 폭 제한 및 제어 유연성 부족 | 코어 수 확장 한계 및 높은 전력 소모 | 범용 연산 불가·고정된 연산 패턴 |

#### 한줄 요약
- 대규모 스레드 병렬은 SIMT, 정형 벡터는 SIMD, 복합 독립 작업은 MIMD, 고정 행렬은 시스톨릭 어레이를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 병합(Memory Coalescing)**: 워프 내 32개 스레드의 메모리 접근 주소가 연속적일 때 하나의 128바이트 트랜잭션으로 결합하는 기술.
- **뱅크 충돌(Bank Conflict)**: 공유 메모리의 동일 뱅크 내 서로 다른 주소를 워프 스레드들이 동시 접근할 때 직렬화되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워프 내 if-else 조건문으로 인한 **분기 발산** | 데이터 정렬·커널 분리로 같은 워프의 실행 경로 통일 | 경로별 직렬 실행 비율 감소 |
| 비연속 메모리 접근으로 인한 트랜잭션 증가 | **메모리 병합(Coalescing)** 및 구조체 배열(SoA) 전환 | 필요한 메모리 트랜잭션 수 감소 |
| 스레드당 과도한 레지스터 사용으로 **점유율(Occupancy)** 저하 | 컴파일러 maxrregcount 옵션 설정 및 변수 수명 최적화 | SM당 동시 상주 워프 수 증가 및 지연 은닉 강화 |
| 공유 메모리 동시 접근 시 **뱅크 충돌(Bank Conflict)** | 패딩으로 스레드별 접근 뱅크 분산 | 직렬화되는 공유 메모리 접근 감소 |

#### 한줄 요약
- 메모리 병합으로 대역폭을 아끼고, 레지스터 최적화로 점유율을 높이며, 패딩으로 뱅크 충돌을 방지한다.

## Ⅶ. 결론

- 독립 데이터가 많고 분기가 균일하면 **SIMT GPU**, 고정 행렬 연산은 **시스톨릭 가속기** 선택
- 분기·불규칙 접근이 지배하면 CPU 병행 또는 알고리즘·데이터 배치 재설계

#### 한줄 요약
- 분기 발산 억제와 메모리 병합, 점유율 극대화를 통해 GPU SIMT 하드웨어의 병렬 처리 잠재력을 최대로 이끌어내야 한다.
