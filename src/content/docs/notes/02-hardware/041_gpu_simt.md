## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **GPU(Graphics Processing Unit)**: 다수 연산 유닛으로 대규모 데이터 병렬 처리를 높은 처리량으로 수행하는 프로세서.
- **SIMT(Single Instruction, Multiple Threads)**: 단일 명령어를 워프 단위의 다수 스레드에 공통으로 발행하여 독립 처리하는 execution 모델.
- **SM(Streaming Multiprocessor)**: 워프 스케줄링, 레지스터 할당, ALU 연산 및 온칩 메모리를 관리하는 GPU 핵심 연산 단위.
- **CPU(Central Processing Unit)**: 복잡한 제어 흐름과 직렬 스레드 처리에 최적화된 범용 프로세서.

- **단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT)**: 다수의 병렬 스레드가 동일한 명령어를 서로 다른 데이터(레지스터)를 바탕으로 락스텝(Lockstep) 실행하는 GPU 하드웨어 실행 모델.
</details>

- 정의/개념: SM이 다수 스레드를 **워프** 단위로 묶어 동일 인스트럭션을 독립 데이터에 분산 발행하는 **SIMT** 모델
- 배경/필요성: CPU 소수 코어 중심 구조의 대규모 텐서/행렬 병렬 연산 처리 한계 극복 필요성

#### 한줄 요약

- GPU는 스레드를 워프로 묶어 같은 명령을 발행하고 준비된 워프를 교대 실행해 대규모 동일 연산의 처리량을 높인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: SIMT 모델에서 하나의 명령을 동기화하여 동시 실행하는 최소 스레드 묶음 단위(보통 32개 스레드).
- **지연 은닉(Latency Hiding)**: 한 워프가 메모리 전송을 대기할 때 다른 준비된 워프를 즉시 교체 스케줄링하여 유휴를 방지하는 기법.
- **활성 마스크(Active Mask)**: 조건 분기 시 현재 인스트럭션을 수행할 스레드 레인을 지정하는 비트 마스크.
- **병합 접근(Coalesced Access)**: 워프 내 인접 스레드의 잇따른 메모리 요청을 1~2회의 대형 트랜잭션으로 통합하는 메모리 기법.
- **점유율(Occupancy)**: SM에 동시 할당된 활성 워프 수 대 하드웨어 최대 허용 워프 수의 백분율.

</details>

- 메모리 전송 지연시간을 획기적으로 가리는 **지연 은닉**
- 조건 분기 발생 시 스레드 분기를 제어하는 **활성 마스크**
- 메모리 대역폭 활용도를 극대화하는 **병합 접근** 및 **점유율** 관리

#### 한줄 요약

- 워프 전환은 메모리 대기 시간을 다른 워프의 실행으로 숨기고, 병합 접근은 전역 메모리 트랜잭션 수를 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워프 스케줄러(Warp Scheduler)**: 매 클록마다 명령어 실행 준비가 끝난 워프를 선정하여 인스트럭션을 디스패치하는 컨트롤러.
- **공유 메모리(Shared Memory)**: 동일 스레드 블록 내부 스레드들이 데이터를 고속 공유·재활용하는 온칩 SRAM.
- **전역 메모리(Global Memory)**: GPU 전체 스레드가 액세스 가능한 대용량 DRAM 영역.
- **L2 캐시(Level 2 Cache)**: 모든 SM이 공통으로 참조하여 전역 메모리 접근 지연을 완화하는 칩 내부 공유 캐시.

</details>

```text
                       [워프 스케줄러]
                               |
                               |
[레지스터•공유 메모리] -- [연산•로드/저장 유닛] -- [L2•전역 메모리]
```

선의 의미: 연산 유닛을 중심으로 상단 스케줄러 제어 신호와 좌우 온칩/오프칩 메모리 계층이 결합된 정적 SM 내부 구조.

| 구성요소 | 책임 |
|:---|:---|
| 워프 스케줄러 | 준비 완료된 워프 선택 및 인스트럭션 제어 파이프라인 디스패치 |
| 연산•로드/저장 유닛 | 산술 연산, 논리 연산 및 메모리 로드/스토어 트랜잭션 수행 |
| 레지스터•공유 메모리 | 스레드 전용 실행 상태 보관 및 블록 내 고속 데이터 공유 |
| L2•전역 메모리 | 모든 SM 간 데이터 일관성 제공 및 최종 텐서 데이터 저장 |

#### 한줄 요약

- 스케줄러가 준비된 워프를 연산 유닛과 메모리 계층에 번갈아 연결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **스레드 블록(Thread Block)**: 동일한 SM에 배정되어 공유 메모리와 바리어 동기화를 사용할 수 있는 스레드 집합.
- **분기 발산(Branch Divergence)**: 워프 내 스레드들이 if-else 조건에 따라 서로 다른 실행 경로로 갈라져 순차 처리되는 현상.

</details>

```text
                    [커널 스레드 블록]
                               |
                    1. SM 배치•자원 할당
                               |
                       [준비 워프 선택]
                               |
           +---------------------------------------+
           | 반복: 블록의 모든 워프 완료 전       |
           | 2. 활성 워프 명령 발행               |
           |              |                        |
           |          [명령 유형]                  |
           |       /       |        \              |
           |    [산술]   [메모리]   [분기]         |
           |      |         |         |             |
           |   [실행]  3. 병합 접근  4. 활성 마스크 실행 |
           |              |                        |
           |        [다음 준비 워프 선택]          |
           +---------------------------------------+
                               |
                    5. 블록 자원 해제
```

### 동작 원리

1. **SM 배치·자원 할당**: **블록 디스패처**가 스레드 블록 요구 레지스터 및 공유 메모리를 확인 후 SM에 할당.
2. **준비 워프 명령 발행**: **워프 스케줄러**가 디스패치 준비 완료된 워프 선택 후 공통 인스트럭션 발행.
3. **메모리 접근 병합**: 전역 메모리 접근 시 워프 스레드 간 인접 주소 패턴을 분석하여 **병합 접근** 트랜잭션 수행.
4. **분기 활성 마스크 실행**: **분기 발산** 시 **활성 마스크**를 적용하여 참/거짓 경로를 개별 순차 실행.
5. **블록 자원 해제**: 블록 내 모든 스레드 실행 완료 시 할당된 자원 해제 및 후속 블록 배치 허용.

#### 한줄 요약

- 준비된 워프를 교대 실행해 메모리 지연을 숨기고, 분기 발산은 경로별 활성 마스크로 순차 처리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIMD(Single Instruction, Multiple Data)**: 하나의 대형 연산자가 여러 데이터 레인에 단일 벡터 인스트럭션을 동시 적용하는 체계.
- **벡터 레인(Vector Lane)**: SIMD 연산기에서 개별 데이터 요소를 병렬 처리하는 일차원 독립 연산 통로.
- **CPU 스레드(CPU Thread)**: 독립적인 제어 및 콘텍스트를 보유하며 복잡한 분기 로직을 빠르게 수행하는 단위.
- **비병합 접근(Uncoalesced Access)**: 스레드 간 메모리 요구 주소가 파편화되어 다수의 개별 메모리 트랜잭션이 유발되는 비효율적 상태.

</details>

| 병렬 실행 방식 | GPU SIMT | CPU SIMD | CPU 스레드 |
|:---|:---|:---|:---|
| 적용 기준 | 대규모 데이터 동일 연산 가속 시 | 수치 행렬/벡터 연산 가속 시 | 복잡한 제어 흐름 및 직렬 처리 시 |
| 핵심 특징 | **SIMT** 기반 워프 스케줄링 | **SIMD** 기반 벡터 레인 정렬 | 독자적 **CPU 스레드** 콘텍스트 |
| 한계 | **분기 발산** 및 **비병합 접근** 지연 | 엄격한 데이터 패킹/정렬 요구 | 스레드 생성 및 콘텍스트 스위칭 비용 |

> 요약: 데이터 병렬성은 SIMT, 단순 벡터화는 SIMD, 복잡 제어는 CPU 적용.

#### 한줄 요약

- 대규모 독립 데이터의 동일 연산은 GPU SIMT, 벡터화 가능한 반복문은 CPU SIMD, 복잡한 독립 제어 흐름은 CPU 스레드가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **레인 활용률(Lane Utilization)**: 워프 32개 레인 중 실제 연산을 유효 수행 중인 스레드의 비율.
- **커널 융합(Kernel Fusion)**: 연관된 복수의 커널 함수를 단일 커널로 통합하여 전역 메모리 통신 오버헤드를 줄이는 기법.
- **비동기 전송(Asynchronous Transfer)**: 호스트-디바이스 간 데이터 전송과 커널 연산 실행을 동시 겹침 처리하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 조건 분기로 인한 **분기 발산** 발생 시 성능 저하 | 동일 분기 조건 기반 데이터 재배치 및 **레인 활용률** 최적화 | 비활성 레인 방치 감소 및 스레드 효율 증대 |
| 불연속 주소 액세스로 인한 **비병합 접근** 감지 | Structure of Arrays(SoA) 구조 전환 및 연속 **병합 접근** 배치 | 전역 메모리 트랜잭션 횟수 단축 |
| 과도한 자원 요구로 인한 SM **점유율** 하락 | 블록당 스레드 수 및 공유 메모리 사용량 미세 조정 | 상주 워프 수 확장으로 **지연 은닉** 강화 |
| 반복적인 호스트-디바이스 간 데이터 송수신 지연 | **커널 융합** 및 CUDA 스트림 기반 **비동기 전송** 적용 | 메인 메모리 I/O 오버헤드 은닉 |

> 사례: 이미지 연산 시 인접 피셀을 연속 스레드에 배치하여 **병합 접근** 패턴 형성

#### 한줄 요약

- 영상 필터는 연속 화소를 같은 워프에 배치해 메모리 요청을 병합하고 분기 발산을 줄인다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동일 연산(Data-Parallel Operation)**: 대규모 입력 요소에 동일 알고리즘을 독립 적용하는 컴퓨팅 형태.
- **실행 장치 선택 기준(Execution Engine Selection Criteria)**: 병렬성 형태, 분기 복잡도, 데이터 액세스 규칙성에 기반한 최적 프로세서 선택 기준.

</details>

- **실행 장치 선택 기준**에 따라 대규모 데이터 병렬 및 높은 규칙성 환경은 **GPU SIMT** 선정

#### 한줄 요약

- 동일 연산이 많고 스레드 주소를 병합할 수 있으면 GPU, 데이터마다 복잡한 분기 경로를 실행하면 CPU 선택 체계 적용.
