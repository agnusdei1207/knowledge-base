## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIMT(Single Instruction, Multiple Threads)**: 수많은 독립 스레드들을 워프(Warp: 32개 스레드) 단위로 묶어 단일 명령어 스트림으로 동시 병렬 실행하는 GPU 하드웨어 실행 모델.
- **GPU(Graphics Processing Unit)**: 수천 개의 소형 고효율 연산 코어와 초고대역폭 메모리(HBM/GDDR)를 집적하여 대규모 데이터 병렬성을 초고속 처리하는 프로세서.

</details>

- 정의/개념: 독립 스레드들을 32개 단위의 **워프(Warp)**로 묶어 단일 명령어로 동시 실행하면서도 스레드별 개별 실행 문맥을 제공하는 **GPU SIMT(Single Instruction, Multiple Threads) 아키텍처**
- 배경/필요성: 소수의 대형 코어와 복잡한 제어 로직 중심의 CPU 구조에 따른 **대규모 AI 딥러닝 텐서 및 3D 그래픽 병렬 연산 처리량 한계 극복**

#### 한줄 요약
- SIMT는 스레드별 독립 제어의 유연성과 SIMD의 대규모 하드웨어 병렬 실행 효율을 동시에 달성하는 GPU 핵심 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워프(Warp)**: SM 내부에서 단일 명령어로 함께 스케줄링되어 락스텝(Lock-step)으로 동시 실행되는 32개 스레드의 하드웨어 실행 단위.
- **지연시간 은닉(Latency Hiding)**: 한 워프가 DRAM 메모리 접근으로 대기할 때, 연산 준비가 완료된 다른 상주 워프로 즉시 스위칭하여 파이프라인 유휴를 없애는 기법.
- **분기 발산(Branch Divergence)**: 워프 내 스레드들이 조건문(if-else)에 따라 서로 다른 분기 경로를 탈 때, 경로별로 순차 직렬 실행되어 성능이 저하되는 현상.

</details>

- 제어 오버헤드 극소화: 32개 스레드가 단일 명령어 인출/디코더를 공유하여 다이 면적당 **순수 연산 코어 집적도 극대화**
- 제로 사이클 문맥 전환: 대용량 온칩 레지스터 파일에 상주 워프 문맥을 통째로 보관하여 **지연시간 은닉(Latency Hiding)** 실현
- 조건 분기 패널티: 워프 내부 스레드의 조건 불일치 시 액티브 마스크를 통해 **분기 발산(Branch Divergence)** 및 순차 실행 발생

#### 한줄 요약
- 워프 공유 실행으로 제어 면적을 줄이고, 대용량 레지스터를 통한 지연 은닉으로 메모리 대기를 무력화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스트리밍 멀티프로세서(Streaming Multiprocessor, SM)**: 워프 스케줄러, 레지스터 파일, CUDA 코어, 텐서 코어, 공유 메모리를 통합 내장한 GPU의 핵심 독립 연산 유닛.
- **공유 메모리(Shared Memory / L1 Data Cache)**: 동일 스레드 블록 내 스레드들이 프로그래머 제어 하에 1~2사이클로 데이터를 초고속 공유하는 온칩 SRAM.

</details>

```text
[GPU 실리콘 프로세서 다이]
 ├─ [스트리밍 멀티프로세서 어레이 (SM 0 ~ SM N)]
 │   ├─ 워프 스케줄러 & 디스패치 유닛 (Warp Schedulers)
 │   ├─ 초거대 온칩 레지스터 파일 (Register File: 수만 개 레지스터 상주)
 │   ├─ 실행 코어군 (FP32, FP64, INT32 코어 + Tensor Core)
 │   ├─ SFU (Special Function Unit: 초월함수 연산기)
 │   └─ [공유 메모리 / L1 캐시 (Shared Memory SRAM)]
 │
 ├─ [온칩 크로스바 인터커넥트]
 ├─ 공유 L2 캐시 (Shared L2 Cache: 수십 MB)
 └─ [고대역폭 메모리 인터페이스 (HBM3 / GDDR6 PHY)] ──► HBM / GDDR DRAM
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 워프 스케줄러가 대용량 레지스터 파일의 워프 문맥을 참조하여 실행 코어로 명령을 발행함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **SM** | GPU 내부 핵심 엔진 | 스레드 블록 수용, 워프 스케줄링, 텐서/벡터 병렬 연산 총괄 | 수십~수백 개 집적 |
| **워프 스케줄러** | SM 내부 제어기 | 매 클록 연산 준비 완료된 워프를 선택하여 연산 코어로 디스패치 | 제로 오버헤드 스위칭 |
| **레지스터 파일** | SM 내부 고속 저장소| 수천 개 상주 스레드의 실행 문맥을 통째로 보관 | 64K~256KB 대용량 SRAM |
| **텐서 코어 (Tensor Core)**| SM 내부 전용 연산기| FP16/INT8/FP8 혼합 정밀도 행렬 곱셈 누산(MMA) 가속 | AI 딥러닝 텐서 가속 |
| **공유 메모리 (Shared)**| SM 내부 온칩 SRAM | 동일 블록 내 스레드 간 초고속 데이터 교환 및 타일링 버퍼 | 프로그래머블 캐시 |

#### 한줄 요약
- GPU는 다수의 SM(워프 스케줄러, 레지스터, 코어, 공유 메모리)과 공유 L2 캐시 및 HBM 메모리 인터페이스로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **액티브 마스크(Active Mask)**: 분기 발산 발생 시 현재 실행 중인 분기 경로에 해당하는 스레드만 1로 인에이블하고 나머지는 일시 비활성화하는 하드웨어 마스크.

</details>

```text
1. 호스트(CPU)의 GPU 커널 함수 런칭 (그리드 및 스레드 블록 구성)
                      │
                      ▼
2. GigaThread 엔진이 스레드 블록들을 각 SM으로 분배 적재
                      │
                      ▼
3. SM 워프 스케줄러: 블록 내 스레드들을 32개씩 워프(Warp)로 그룹화
                      │
                      ▼
4. 실행 가능한 준비 완료(Ready) 워프 탐색
   ┌──────────────────┴──────────────────┐
[ 준비 완료 워프 존재 ]               [ 모든 워프가 메모리 접근 대기 중 ]
   │                                     │
   ▼                                     ▼
5. 1개 명령어를 32개 코어로 동시 발행   6. 연산 파이프라인 일시 정지 (지연 은닉 실패)
   │
   ▼
7. 워프 내 스레드 간 분기 일치 여부 검사
   ┌──────────────────┴──────────────────┐
[ 전 스레드 동일 분기 (No Divergence) ] [ if-else 분기 발산 (Divergence) ]
   │                                     │
   ▼                                     ▼
8. 32개 코어 100% 동시 실행 완료        9. 액티브 마스크 설정 ➔ if 경로 실행 (else 스레드 유휴)
                                         │  ➔ else 경로 순차 실행 (if 스레드 유휴)
   └──────────────────┬──────────────────┘
                      │
                      ▼
10. 메모리 접근 대기 발생 시 ➔ 1사이클 내에 다른 대기 워프로 스위칭 (지연시간 은닉)
```

분기 결과: **분기 발산이 없으면** 32스레드가 100% 동시 실행되나, **발산 발생 시** 경로 수만큼 순차 실행되어 연산 효율이 저하됨

#### 한줄 요약
- 블록 적재 ➔ 워프 스케줄링 ➔ 단일 명령어 32코어 동시 발행 ➔ 분기 발산 시 마스크 순차 실행 ➔ 메모리 대기 시 타 워프 스위칭 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 병렬 처리 아키텍처 | SIMT (GPU 아키텍처) | SIMD (CPU 벡터 확장: AVX-512) | MIMD (멀티코어 CPU) |
|:---|:---|:---|:---|
| 프로그래밍 모델 | **스레드 수준 병렬성 (Thread-Level)** | 데이터 벡터 레지스터 병렬성 | 독립 태스크/스레드 병렬성 |
| 명령어 제어 | **32개 독립 스레드가 단일 명령어 공유** | 단일 명령어가 단일 벡터 레지스터 구동 | **각 코어가 독립된 명령어 스트림 실행** |
| 분기 처리 능력 | **하드웨어 액티브 마스크로 분기 발산 처리** | 벡터 마스크 레지스터(K-Mask) 수동 제어 | 각 코어가 독립 분기 예측 및 실행 |
| 연산 병렬 규모 | **수만~수십만 개 스레드 동시 상주** | 8~16개 데이터 요소 벡터화 | 수십~수백 개 코어 병렬 실행 |
| 주요 적용 분야 | **AI 딥러닝 훈련/추론, 3D 그래픽 렌더링** | 과학 계산, 오디오/비디오 인코딩 루프 | 범용 OS, 데이터베이스 트랜잭션, 웹 서버 |

#### 한줄 요약
- SIMD는 단일 벡터 레지스터에 종속되고 MIMD는 코어 확장이 제한적인 반면, SIMT는 수만 스레드의 대규모 데이터 병렬성을 완벽히 처리한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 병합(Memory Coalescing)**: 워프 내 32개 스레드의 연속 메모리 접근을 단 1회의 128바이트 DRAM 트랜잭션으로 결합하는 최적화.
- **뱅크 충돌(Bank Conflict)**: 공유 메모리의 동일 뱅크에 서로 다른 주소 접근이 동시 발생하여 접근이 직렬화되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 워프 내 분기 발산(Branch Divergence)으로 인한 연산기 유휴 | **데이터 정렬 및 워프 단위 커널 분할(Warp-Specialized)** | 분기 발산 제거 및 연산 코어 가동률 95% 달성 |
| 비연속 메모리 스트라이드로 인한 메모리 대역폭 낭비 | **구조체 배열(AoS)을 배열 구조체(SoA)로 전환하여 메모리 병합** | DRAM 읽기 트랜잭션 80% 감소 |
| 과도한 스레드당 레지스터 사용으로 인한 SM 점유율(Occupancy) 저하 | **컴파일러 launch_bounds 지정 및 레지스터 수 제한** | SM당 상주 워프 수 극대화 및 지연 은닉 완성 |
| 공유 메모리 접근 시 발생하는 **뱅크 충돌(Bank Conflict)** | **공유 메모리 2차원 배열 열 패딩(Padding: +1) 삽입** | 동시 접근 직렬화 제거 및 1사이클 메모리 공급 |

#### 한줄 요약
- 실무에서는 메모리 병합(Coalescing), 워프 특화 분기 제거, 공유 메모리 패딩을 통해 GPU 대역폭과 점유율을 극대화한다.

## Ⅶ. 결론

- 대규모 AI 딥러닝 및 그래픽 연산의 병렬 처리량을 극대화하기 위해 **수만 스레드를 초고속 스케줄링하는 SIMT(Single Instruction, Multiple Threads) 기반 GPU 아키텍처를 표준 채택**하고, 하드웨어 성능을 100% 이끌어내기 위해 **메모리 병합(Coalescing)과 공유 메모리 타일링 최적화**를 적용하며, 최신 AI 가속을 위해 **혼합 정밀도 텐서 코어(Tensor Core)와 HBM3 인터페이스**를 융합하는 고성능 가속 컴퓨팅 시스템 구축

#### 한줄 요약
- SIMT는 현대 AI와 고성능 컴퓨팅의 표준 실행 모델이며, 데이터 레이아웃 최적화와 텐서 코어 활용을 통해 압도적 처리량을 완성한다.
