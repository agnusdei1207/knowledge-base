## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 모든 코어가 공유 통신 선로(Bus)를 상시 감시(Snoop)하여 자신의 캐시 사본과 일치하는 주소의 트랜잭션이 발생할 때 즉시 무효화/갱신을 수행하는 방식.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 각 메모리 블록의 공유 상태와 사본 보유 노드 목록(Sharer Mask)을 디렉터리 테이블에 기록하고, 점대점 패킷 메시지로 일관성을 유지하는 방식.
- **브로드캐스트 폭풍(Broadcast Storm)**: 코어 수가 증가함에 따라 모든 코어로 무차별 전송되는 스누프 요청이 버스 대역폭을 완전히 고갈시키는 현상.

</details>

- 정의/개념: 멀티코어 및 분산 공유 메모리 환경에서 데이터 일관성을 유지하기 위해 공유 버스 브로드캐스트를 활용하는 **버스 스누핑**과 공유자 목록 테이블을 참조하여 점대점 통신하는 **디렉터리 기반 프로토콜**로 대별되는 캐시 일관성 아키텍처
- 배경/필요성: 코어 수 증가에 따라 모든 노드로 스누프 요청을 전송하는 브로드캐스트 트래픽 급증(**브로드캐스트 폭풍**) 및 인터커넥트 대역폭 포화로 인한 대규모 멀티프로세서 확장성 한계 해소

#### 한줄 요약
- 소규모 멀티코어는 버스 스누핑으로 초저지연을 달성하고, 대규모 NUMA 시스템은 디렉터리 방식으로 확장성을 확보한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공유자 비트마스크(Sharer Bitmask)**: 특정 메모리 블록을 캐시에 보유하고 있는 노드들의 ID를 1비트씩 매핑한 디렉터리 엔트리 필드.
- **3-Hop 메시지 교환**: 요청자 노드 $\to$ 홈 노드 $\to$ 소유자/공유자 노드 $\to$ 요청자 노드로 이어지는 디렉터리 기반 일관성의 통신 경로.
- **NUMA(Non-Uniform Memory Access)**: 프로세서가 접근하는 메모리의 물리적 위치(로컬 소켓 vs 원격 소켓)에 따라 접근 지연시간이 달라지는 분산 공유 메모리 아키텍처.

</details>

- 브로드캐스트 대 점대점 통신: 스누핑은 공유 버스 **브로드캐스트**로 전송하고, 디렉터리는 **점대점 유니캐스트**로 선택 전송
- 확장성과 하드웨어 오버헤드 상충: 스누핑은 디렉터리 메모리가 없으나 소규모 코어로 제한되고, 디렉터리는 **디렉터리 비트마스크** 메모리가 필요하나 대규모 확장 가능
- 지연시간 특성: 스누핑은 1회의 버스 트랜잭션으로 **최저 지연**을 달성하며, 디렉터리는 홈 노드를 경유하는 **3-Hop 메시지 교환** 지연 발생

#### 한줄 요약
- 스누핑은 방송 기반으로 빠르지만 확장성이 낮고, 디렉터리는 목록 기반으로 대역폭을 아끼지만 3-Hop 지연이 발생한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **홈 디렉터리(Home Directory)**: 특정 물리 메모리 주소 영역의 일관성 상태, 소유자 정보, 공유자 목록을 전담 관리하는 하드웨어 테이블.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 노드 간 직접 연결 또는 라우팅 스위치를 통해 필요한 대상 노드와만 1:1로 통신하는 패킷 기반 고속 인터커넥트망(UPI, Infinity Fabric 등).

</details>

```text
[캐시 일관성 구현 아키텍처]
  │
  ├─ [버스 스누핑 방식 (소규모 SMP)]
  │     ├─ [공유 버스] (브로드캐스트 전송로)
  │     └─ [스누프 제어기] (버스 트랜잭션 상시 감시)
  │
  └─ [디렉터리 방식 (대규모 NUMA)]
        ├─ [홈 디렉터리] (공유자 비트마스크 추적)
        └─ [점대점 인터커넥트] (유니캐스트 패킷 라우팅)
```

선의 의미: 버스 스누핑 방식과 디렉터리 방식의 핵심 하드웨어 구성요소 계층을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 공유 버스 | 모든 코어에 일관성 트랜잭션을 일괄 **브로드캐스트**하여 순서 보장 |
| 스누프 제어기 | 방송 주소를 상시 감시하여 일치 시 로컬 캐시 **상태 전이** 및 무효화 수행 |
| 홈 디렉터리 | 블록별 **공유자 목록**과 소유자 상태를 비트마스크로 추적 및 관리 |
| 점대점 인터커넥트 | 요청자, 홈 노드, 공유자 간 유니캐스트 패킷을 라우팅하여 버스 병목 차단 |

#### 한줄 요약
- 스누핑은 모든 코어가 공유 버스를 매개로 연결되고, 디렉터리는 홈 노드의 비트마스크를 통해 점대점 인터커넥트로 연결된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **홈 노드(Home Node)**: 요청 주소의 물리 메모리와 디렉터리 엔트리를 보유한 기준 노드.
- **요청자 노드(Requester Node)**: 데이터 읽기 또는 쓰기를 요청한 CPU 코어 노드.

</details>

```text
[공유 캐시 라인 쓰기 동작 요청]
               │
               ▼
      1. 일관성 메커니즘 판정
   ┌───────────┴───────────┐
(버스 스누핑 방식)       (디렉터리 기반 방식)
   │                       │
   ▼                       ▼
2. 공유 버스 BusRdX 전송 3. 홈 노드 디렉터리 조회
(전체 코어 브로드캐스트) (공유자 비트마스크 판별)
   │                       │
   ▼                       ▼
타 코어 즉시 무효화      4. 사본 보유 코어에만 점대점 무효화
   │                       │ (Ack 응답 수합)
   └───────────┬───────────┘
               │
               ▼
[독점(M) 권한 획득 후 로컬 캐시 쓰기 완료]
```

분기 결과: 스누핑은 **단일 버스 트랜잭션**으로 처리하고, 디렉터리는 **3-Hop 점대점 메시지 교환**으로 처리함

**동작 원리**

1. **쓰기 권한 획득 요청**: 코어가 사설 캐시 내 공유 블록에 쓰기를 시도할 때 일관성 제어기에 쓰기 권한 요청을 발행함
2. **스누핑 브로드캐스트 및 즉시 무효화**: 버스 스누핑 구조에서는 공유 버스에 BusRdX 신호를 브로드캐스트하여 모든 코어의 캐시 사본을 즉시 무효화함
3. **홈 디렉터리 조회 및 타깃 무효화**: 디렉터리 구조에서는 홈 노드로 요청을 전송하고, 홈 디렉터리의 공유자 비트마스크를 확인하여 실제 사본을 가진 노드에만 유니캐스트 무효화 패킷을 발송함
4. **무효화 응답 수합 및 쓰기 완료**: 디렉터리 구조에서 대상 노드들의 무효화 완료 응답(Ack)을 모두 수합한 후 요청자 코어가 독점(M) 권한을 얻어 쓰기를 완료함

#### 한줄 요약
- 스누핑은 1번의 방송으로 처리하고, 디렉터리는 요청자 ➔ 홈 노드 ➔ 공유자 ➔ 요청자의 3-Hop 점대점 통신으로 처리한다.

## Ⅴ. 종류 및 비교

| 캐시 일관성 아키텍처 | 버스 스누핑 (Bus Snooping) | 디렉터리 기반 일관성 (Directory-Based) |
|:---|:---|:---|
| 적용 기준 | **소규모 코어(단일 소켓)** 및 초저지연 요구 | **대규모 멀티소켓(NUMA)** 및 높은 확장성 요구 |
| 핵심 특징 | 공유 버스 기반 **브로드캐스트 트랜잭션** | 점대점 인터커넥트 기반 **유니캐스트 라우팅** |
| 한계 | 코어 수 증가 시 **버스 대역폭 포화** | 홈 노드 경유에 따른 **3-Hop 지연 및 메모리 오버헤드** |

#### 한줄 요약
- 단일 칩 소규모 시스템에는 버스 스누핑이, 대규모 다중 소켓 서버 및 NUMA 시스템에는 디렉터리 기반 일관성이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 전체 메인 메모리가 아닌 현재 캐시 계층에 적재된 블록에 대해서만 디렉터리 엔트리를 동적 할당하는 캐시형 디렉터리 구조.
- **주소 해싱(Address Hashing)**: 메모리 주소를 해시 함수로 분산하여 홈 노드를 전체 소켓에 균등하게 분배함으로써 핫스팟 병목을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 디렉터리 비트마스크 저장으로 인한 메모리 오버헤드 | **희소 디렉터리** 구조 적용 | 디렉터리 메모리 점유율을 DRAM의 1% 미만으로 절감 |
| 특정 홈 노드로 메모리 요청이 집중되는 핫스팟 현상 | 인터커넥트 **주소 해싱** 적용 | 소켓 간 트래픽 균등 분산 및 대역폭 포화 방지 |
| 소규모 칩렛 간 통신에서 디렉터리 3-Hop 지연 오버헤드 | **하이브리드 계층형 일관성** 구축 | 로컬 저지연과 글로벌 확장성의 최적 절충 |

#### 한줄 요약
- 실무에서는 희소 디렉터리로 메모리를 아끼고, 주소 해싱으로 핫스팟을 분산하며, 계층형 하이브리드 일관성으로 지연과 확장성을 절충한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **칩렛(Chiplet)**: 단일 다이 제조 한계를 넘어 독립적으로 생산된 소형 기능 다이들을 하나의 패키지 기판 위에 고밀도 연결하는 기술.
- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: 고속 PCIe 물리 계층을 기반으로 CPU와 장치 간 캐시 일관성 및 메모리 풀링을 지원하는 개방형 표준 인터커넥트.

</details>

- 단일 소켓·소규모 코어 환경의 버스 스누핑과 대규모 NUMA 환경의 디렉터리 방식이 상호 보완적 표준으로 확립되었으며, 멀티 **칩렛(Chiplet)** 모듈화 및 **컴퓨트 익스프레스 링크(CXL)** 기반 이기종 메모리 풀링 환경에서는 소켓 내 스누핑과 소켓 간 디렉터리를 유기적으로 결합한 계층형 하이브리드 일관성 아키텍처로 진화하는 추세.
- 시스템 확장 시 발생하는 디렉터리 비트마스크 메모리 점유와 3-Hop 트랜잭션 왕복 지연을 억제하기 위해, 노드 간 인터커넥트 대역폭을 고려한 희소 디렉터리 캐시 크기 최적화 및 주소 해싱 기반 트래픽 분산 설계 역량 확보 필요.

#### 한줄 요약
- 스누핑과 디렉터리는 칩렛 및 CXL 환경에서 계층형 하이브리드로 융합되고 있으며, 3-Hop 지연과 디렉터리 메모리 오버헤드를 제어하는 분산 최적화가 핵심이다.
