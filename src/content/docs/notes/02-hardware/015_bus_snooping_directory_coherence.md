## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 각 캐시 제어기가 공유 버스의 일관성 트랜잭션을 관찰해 자신의 상태를 갱신하는 방식입니다.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 메모리 블록별 캐시 보유자 목록을 디렉터리에 기록하고 필요한 노드에만 메시지를 보내는 방식입니다.
- **브로드캐스트(Broadcast)**: 하나의 요청을 모든 일관성 참여자에게 동시에 전달하는 통신 방식입니다.

</details>

- 정의/개념: 공유 버스 관찰 또는 보유자 목록 조회로 **캐시 일관성**을 조정하는 방식
- 배경/필요성: 코어 증가에 따른 브로드캐스트 트래픽과 일관성 지연 절충

#### 한줄 요약

- 스누핑은 모두에게 물어보고, 디렉터리는 실제 사본을 가진 코어만 찾아 물어보는 일관성 방식입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공유자 목록(Sharer List)**: 특정 메모리 블록을 캐시에 보유한 코어들의 목록입니다.
- **선택적 무효화(Selective Invalidation)**: 공유자 목록에 있는 캐시만 대상으로 사본을 무효화하는 처리입니다.
- **확장성(Scalability)**: 코어 수가 증가해도 통신량과 처리 지연을 감당하며 시스템을 확장하는 성질입니다.

</details>

- 스누핑: 전 참여자가 요청을 관찰하는 **브로드캐스트 일관성**
- 디렉터리: 공유자 목록을 이용하는 **선택적 무효화**
- 구조 선택: 코어 수와 **확장성**에 따른 통신 방식 결정

#### 한줄 요약

- 참여자가 적으면 전체 방송이 단순하지만, 코어가 많아지면 실제 공유자만 겨냥하는 방식이 통신량을 줄일 수 있습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스누프 제어기(Snoop Controller)**: 버스에 나타난 요청을 검사하고 캐시 라인 상태를 전이시키는 제어기입니다.
- **홈 디렉터리(Home Directory)**: 메모리 블록의 공유자와 소유 상태를 관리하는 디렉터리 위치입니다.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 필요한 노드 사이에만 일관성 메시지를 전달하는 연결망입니다.

</details>

```text
[일관성 연결 구조]
├─ 버스 스누핑
│  ├─ 공유 버스
│  └─ 스누프 제어기
└─ 디렉터리 기반
   ├─ 홈 디렉터리
   └─ 점대점 인터커넥트
```

| 구성요소 | 책임 |
|:---|:---|
| 공유 버스 | 일관성 요청의 전체 전달 |
| 스누프 제어기 | 방송 요청 관찰과 캐시 상태 갱신 |
| 홈 디렉터리 | 블록별 공유자·소유자 정보 관리 |
| 점대점 인터커넥트 | 대상 노드 간 메시지 전달 |

#### 한줄 요약

- 스누핑은 공유 매체와 관찰 제어기가 핵심이고, 디렉터리는 공유자 정보를 저장할 홈과 대상 전송망이 핵심입니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **무효화 응답(Invalidation Acknowledgement)**: 캐시가 사본을 무효화한 뒤 요청자에게 완료를 알리는 응답입니다.
- **홈 노드(Home Node)**: 특정 메모리 주소와 디렉터리 정보를 담당하는 노드입니다.

</details>

```text
[1. 쓰기 요청]
          │
          ├─ 스누핑: 공유 버스 방송
          │          │
          │          ▼
          │     [2. 모든 캐시 관찰]
          │
          └─ 디렉터리: 홈 노드 조회
                     │
                     ▼
                [2. 공유자 특정]
                     │
                     ▼
                [3. 대상 무효화·응답]
          │
          ▼
[4. 쓰기 권한 확정]
```

동작 원리:

1. 쓰기 요청: 코어가 공유 캐시 라인의 수정 권한 요청
2. 모든 캐시 관찰 또는 공유자 특정: 방식별 대상 확인
3. 대상 무효화·응답: 기존 사본 제거와 완료 응답 수합
4. 쓰기 권한 확정: 요청 코어에 독점 수정 권한 부여

#### 한줄 요약

- 스누핑은 모든 캐시가 스스로 해당 여부를 판단하고, 디렉터리는 홈 노드가 대상자를 골라 무효화를 진행합니다.

## Ⅴ. 종류 및 비교

| 일관성 방식 | 버스 스누핑 | 디렉터리 기반 |
|:---|:---|:---|
| 적용 기준 | 참여 코어가 적고 공유 버스가 충분한 경우 | 코어·소켓 수가 많고 대상 지정이 필요한 경우 |
| 핵심 특징 | 전체 참여자의 요청 관찰 | 공유자 목록 기반 선택 전송 |
| 한계 | 코어 증가에 따른 방송 트래픽 증가 | 디렉터리 저장 공간과 조회 지연 |

#### 한줄 요약

- 스누핑은 단순한 대신 방송 비용을 지고, 디렉터리는 확장되는 대신 공유자 정보를 저장하고 조회해야 합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 실제로 캐시된 블록 중심으로 디렉터리 정보를 할당해 저장 공간을 줄이는 구조입니다.
- **가상 채널(Virtual Channel)**: 요청·응답처럼 다른 메시지 큐를 분리해 인터커넥트 교착을 줄이는 기법입니다.
- **주소 해싱(Address Hashing)**: 주소를 여러 홈 노드에 분산해 특정 디렉터리로 요청이 몰리는 현상을 줄이는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스누핑 방송이 코어 증가로 포화 | 계층형 스누핑 또는 디렉터리 전환 | 방송 범위와 버스 혼잡 감소 |
| 디렉터리 공유자 정보가 커짐 | 희소 디렉터리와 제한 목록 적용 | 메타데이터 면적 절감 |
| 특정 홈 노드에 요청 집중 | 주소 해싱으로 홈 노드 분산 | 일관성 지연과 핫스팟 완화 |
| 요청·응답 순환으로 인터커넥트 교착 | 가상 채널과 메시지 순서 규칙 적용 | 프로토콜 진행성 확보 |

#### 한줄 요약

- 스누핑은 방송 범위를 줄이고, 디렉터리는 메타데이터와 라우팅 병목을 줄이는 방향으로 대책을 세웁니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **계층형 일관성(Hierarchical Coherence)**: 칩 내부와 소켓 사이처럼 범위별로 다른 일관성 방식을 조합하는 구조입니다.

</details>

- 코어 수와 **일관성 트래픽**이 작으면 버스 스누핑을, 대규모·NUMA 환경이면 디렉터리 또는 계층형 일관성을 선택하고 메타데이터·지연 비용을 함께 결정

#### 한줄 요약

- 일관성 방식은 코어 수만 보고 정하지 않고, 모든 코어에 방송할 비용과 공유자 목록을 관리할 비용 중 작은 쪽을 선택합니다.
