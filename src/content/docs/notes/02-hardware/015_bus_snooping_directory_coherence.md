## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **버스 스누핑(Bus Snooping)**: 공유 버스 요청을 모든 캐시가 감시하는 일관성 구현 방식.
- **디렉터리 일관성(Directory Coherence)**: 디렉터리가 라인별 공유자를 추적하는 일관성 구현 방식.
- **선택적 무효화(Selective Invalidation)**: 쓰기 대상 라인의 사본을 가진 캐시에만 권한 회수 요청을 보내는 동작.
- **공유자 추적(Sharer Tracking)**: 각 캐시 라인의 읽기 사본을 가진 캐시나 노드의 위치를 관리 정보로 기록하는 방식.

</details>

- 정의/개념: 일관성 요청을 전체에 방송하는 **버스 스누핑**과 **공유자 추적**으로 관련 노드에만 요청하는 **디렉터리 일관성**
- 배경/필요성: 대규모 분산·대칭형 멀티프로세서에서 전역 버스 방송 방식은 트래픽 폭증으로 확장성 저해

#### 한줄 요약

- 쓰기 권한을 얻으려면 다른 사본을 모두 무효화해야 하므로, 스누핑과 디렉터리는 사본 위치를 찾는 방식에서 갈린다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **일관성 순서점(Coherence Ordering Point)**: 같은 라인에 대한 요청의 전역 순서를 확정하는 버스나 홈 디렉터리.
- **무효화 응답(Invalidation Acknowledgment)**: 캐시가 사본을 버렸음을 알리는 완료 메시지.
- **배타적 쓰기 권한(Exclusive Write Permission)**: 특정 캐시 하나만 해당 라인을 수정할 수 있도록 보장하는 권한.
- **방송 관찰(Broadcast Observation)**: 일관성 요청을 모든 캐시에 보내고 각 캐시가 관련 사본이 있는지 직접 확인하는 방식.
- **명단 조회(Directory Lookup)**: 디렉터리의 공유자 목록을 확인해 관련 캐시에만 요청을 보내는 방식.

</details>

- 같은 라인 요청을 **일관성 순서점** 하나로 직렬화
- **무효화 응답** 수합 후에만 **배타적 쓰기 권한** 부여
- 사본 보유 노드를 **방송 관찰** 또는 **명단 조회**로 식별

#### 한줄 요약

- 두 방식 모두 무효화 완료를 모은 뒤 쓰기를 허용하며, 요청을 전체에 방송할지 공유자에게만 보낼지가 다르다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **버스 중재기(Bus Arbiter)**: 공유 버스 요청의 전역 처리 순서를 정하는 회로.
- **스누프 제어기(Snoop Controller)**: 버스 주소를 감시하고 관련 캐시 사본을 제어하는 회로.
- **홈 디렉터리(Home Directory)**: 블록마다 최신 소유자와 읽기 공유자 명단을 보관하는 관리 구조.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 송수신 노드를 지정해 관련 캐시에만 메시지를 전달하는 연결망.
- **공유 버스(Shared Bus)**: 여러 캐시가 하나의 전송 경로를 함께 사용하며 모든 요청을 관찰하는 연결 구조.
- **노드(Node)**: 코어•캐시•메모리 제어기처럼 일관성 연결망에서 메시지를 송수신하는 구성 단위.

</details>

```text
일관성 구현 구조
├─ 버스 스누핑
│  ├─ 공유 버스·중재기
│  └─ 스누프 제어기
└─ 디렉터리 방식
   ├─ 홈 디렉터리
   └─ 점대점 인터커넥트
```

가지의 의미: 전체 방송과 지정 전달 방식의 정적 구성 차이.

| 구성요소 | 책임 |
|:---|:---|
| **공유 버스**•**버스 중재기** | 요청 직렬화와 전체 방송 |
| **스누프 제어기** | 사본 무효화•데이터 응답 |
| **홈 디렉터리** | 소유자•공유자 추적 |
| **점대점 인터커넥트** | 관련 **노드**에 지정 전달 |

#### 한줄 요약
- 스누핑은 버스와 제어기가 전체에 알리고 디렉터리는 명단과 인터커넥트로 관련 캐시에만 전달한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **소유자(Owner)**: 최신 수정본과 메모리 반영 책임을 가진 캐시.
- **공유자(Sharer)**: 읽기 전용 캐시 사본을 가진 캐시.
- **공유자 목록(Sharer List)**: 쓰기 전 무효화 요청을 보내야 할 캐시들의 명단.
- **완료 응답 수합(Acknowledgment Collection)**: 모든 대상 캐시의 무효화 확인을 모은 뒤 쓰기 권한을 내주는 절차.
- **홈 노드(Home Node)**: 특정 메모리 주소의 디렉터리 정보와 일관성 요청 순서를 책임지는 노드.

</details>

```text
쓰기 권한 요청
      │
      ▼
1. 무효화 대상 식별
├─ 버스 스누핑: 전체 캐시에 방송
└─ 디렉터리 방식: 공유자 명단 조회·지정 전달
      │
      ▼
2. 무효화 요청 전달
      │ 대상 캐시별 반복
      ▼
3. 무효화 완료 응답
      │
      ▼
4. 쓰기 소유권 부여
```

### 동작 원리

1. **무효화 대상 식별**: 전체 방송 또는 **공유자 목록** 조회로 사본 보유 캐시 식별.
2. **무효화 요청 전달**: 식별한 캐시에서 해당 라인의 읽기 권한 회수.
3. **무효화 완료 응답**: 모든 대상 캐시의 권한 회수 통보를 **완료 응답 수합** 절차로 수집.
4. **쓰기 소유권 부여**: 모든 무효화 완료 확인 후 요청 캐시에 배타적 쓰기 권한 부여.

#### 한줄 요약

- 스누핑은 공유 버스가 요청 순서를 정하고, 디렉터리는 홈 노드가 공유자와 소유권을 관리한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **디렉터리 방식(Directory-Based)**: 공유자 정보를 조회해 관련 노드에만 요청을 지정 전달하는 방식.
- **메타데이터(Metadata)**: 소유자•공유자와 권한 상태를 기록하는 관리 정보.
- **다중 소켓(Multi-Socket)**: 여러 프로세서 패키지가 하나의 시스템 메모리 공간을 공유하는 구성.
- **조회 지연(Lookup Latency)**: 디렉터리에서 소유자•공유자 정보를 찾고 요청 대상을 결정하는 데 걸리는 시간.
- **버스 포화(Bus Saturation)**: 방송량이 공유 버스의 전송 한계에 도달해 코어를 늘려도 대기만 증가하는 상태.

</details>

| 일관성 구현 방식 | 버스 스누핑 | 디렉터리 방식 |
|:---|:---|:---|
| 적용 기준 | 소규모 코어가 **공유 버스** 사용 시 | **다중 소켓**·대규모 노드에서 방송 비용 클 때 |
| 핵심 특징 | 전체 캐시의 **방송 관찰** | 명단 기반 지정 전달 |
| 한계 | 노드 증가에 따른 **버스 포화** | 공유자 추적 **메타데이터**•**조회 지연** |

> 요약: 스누핑의 방송 한계를 디렉터리가 공유자 명단 관리 비용으로 대체.

#### 한줄 요약

- 스누핑은 노드 증가 시 방송 경로가 포화되고, 디렉터리는 방송을 줄이는 대신 명단 용량과 조회 지연을 부담한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **희소 디렉터리(Sparse Directory)**: 공유자 정보만 압축해 메타데이터를 줄이는 구조.
- **제한 디렉터리(Limited Directory)**: 추적 가능한 공유자 수를 제한해 메타데이터를 줄이는 구조.
- **비균일 메모리 접근(Non-Uniform Memory Access, NUMA)**: 노드 위치에 따라 메모리 지연이 달라지는 구조.
- **NUMA 인지 배치(NUMA-Aware Placement)**: 데이터와 처리 코어를 가까운 메모리 노드에 배치하는 방법.
- **스누핑 계층화(Snooping Hierarchy)**: 코어를 여러 그룹으로 나누고 그룹 안과 사이의 방송 범위를 구분해 전체 방송량을 줄이는 구조.
- **공유자 비트맵(Sharer Bitmap)**: 각 노드의 사본 보유 여부를 비트 하나씩으로 표시하는 디렉터리 자료 구조.
- **주소 해싱(Address Hashing)**: 주소 비트를 혼합해 홈 디렉터리를 여러 노드에 분산하는 방법.
- **프로토콜 교착(Protocol Deadlock)**: 일관성 요청과 응답이 버퍼나 자원을 서로 기다려 진행하지 못하는 상태.
- **가상 채널(Virtual Channel)**: 요청·응답 메시지 종류별 전송 경로를 논리적으로 분리해 순환 대기를 방지하는 통신 자원.
- **활성(Liveness)**: 모든 일관성 요청이 결국 완료되어야 한다는 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 방송 요청 증가로 **버스 포화** | **스누핑 계층화**•디렉터리 전환으로 방송 범위 축소 | 코어 확장성 확보 |
| 노드 수에 따른 **공유자 비트맵** 용량 증가 | **희소 디렉터리**•**제한 디렉터리**로 정보 압축 | 메타데이터 절감 |
| 특정 **홈 노드**에 요청 집중 | **주소 해싱**•**NUMA 인지 배치**로 요청 분산 | 원격 조회 지연 감소 |
| 요청•응답이 버퍼를 서로 기다리는 **프로토콜 교착** | 메시지별 **가상 채널**•자원 순서 분리 | **활성** 유지 |

#### 한줄 요약

- 소규모 공유 버스에서는 방송 비용이 낮아 스누핑이 단순하고, 노드가 늘어 방송이 포화되면 디렉터리의 지정 전달이 유리하다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **방송 확장성(Broadcast Scalability)**: 모든 캐시에 요청을 보내는 방식이 노드 증가에도 처리량을 유지하는 능력.
- **지정 전달(Directed Forwarding)**: 디렉터리가 알려 준 소유자와 공유자에게만 일관성 메시지를 보내는 방식.
- **구현 방식 선택 기준**: 노드 수와 방송 확장성으로 스누핑과 디렉터리 방식을 고르는 기준.

</details>

- **구현 방식 선택 기준**에 따라 **방송 확장성** 충분한 소규모 공유 버스는 **스누핑**, 방송 포화 시에는 **디렉터리**의 **지정 전달** 선택

#### 한줄 요약

- 소규모 공유 버스는 스누핑을 쓰고, 방송 포화로 확장성이 막히면 디렉터리의 지정 전달로 전환한다.
