## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 모든 캐시 제어기가 공유 버스를 지속적으로 감시(Snoop)하여 타 코어의 읽기/쓰기 트랜잭션 발생 시 자신의 캐시 상태를 동기화하는 브로드캐스트 기반 일관성 유지 기법.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 각 메모리 블록의 공유 상태 및 보유 노드 목록(Sharer Mask)을 디렉터리에 기록 관리하고, 변경 시 해당 공유자에게만 점대점으로 유니캐스트/멀티캐스트 메시지를 전송하는 일관성 기법.
- **브로드캐스트(Broadcast)**: 단일 노드가 발생시킨 메시지나 트랜잭션을 시스템 내의 모든 연결 노드에게 동시에 전파하는 통신 방식.

</details>

- 정의/개념: 모든 캐시가 요청을 관찰하는 **버스 스누핑** 및 보유자만 골라 통지하는 **디렉터리 기반 일관성**으로 갈리는 일관성 구현 방식
- 배경/필요성: 코어가 늘면 **브로드캐스트** 요청 수가 코어 수에 비례해 늘어 공유 버스가 먼저 포화

#### 한줄 요약
- 두 방식의 갈림길은 사본이 어디 있는지를 기억해 두느냐이며, 기억하지 않으면 매번 전부에게 묻고 기억하면 그 기억을 저장할 공간이 필요해진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공유자 목록(Sharer List)**: 특정 메모리 블록의 유효 사본을 현재 보유하고 있는 프로세서 코어 또는 캐시 노드들의 비트맵(Bitmask) 목록.
- **선택적 무효화(Selective Invalidation)**: 전체 노드에 방송하지 않고 디렉터리의 공유자 목록에 등재된 특정 캐시 노드에게만 점대점으로 무효화 요청을 전송하는 기법.
- **확장성(Scalability)**: 프로세서 코어 수가 수십~수천 개로 증가해도 인터커넥트 트래픽과 지연시간이 폭증하지 않고 성능이 선형적으로 유지되는 아키텍처 특성.

</details>

- 버스 스누핑: 상태를 따로 저장하지 않아 구현이 단순하나 코어 증가 시 트래픽이 선형 이상으로 증가
- 디렉터리: **공유자 목록** 기반 **선택적 무효화**를 통해 트래픽을 줄이는 대신 조회 왕복이 지연에 추가
- 두 방식 모두 정확성은 동일하며 차이는 **확장성** 한 축에서만 발생

#### 한줄 요약
- 스누핑은 지연이 짧고 대역폭을 많이 쓰며 디렉터리는 그 반대이므로, 코어 수가 적을 때는 디렉터리가 오히려 느리다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스누프 제어기(Snoop Controller)**: 공유 버스 상의 주소 및 제어 신호를 실시간 스누핑하여 태그 비교 및 로컬 캐시 라인의 상태 전이를 수행하는 하드웨어 제어 로직.
- **홈 디렉터리(Home Directory)**: 특정 물리 메모리 주소 영역의 일관성 상태, 소유자 정보, 공유자 목록을 전담 관리하도록 지정된 디렉터리 저장소.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 노드 간 직접 연결 또는 라우팅 스위치를 통해 필요한 대상 노드와만 1:1로 통신하는 패킷 기반 고속 인터커넥트망(UPI, Infinity Fabric 등).

</details>

```text
[버스 스누핑]
코어 0 ─ 캐시·스누프 제어기 ─┐
코어 1 ─ 캐시·스누프 제어기 ─┼─ 공유 버스
             ···             ┘

[디렉터리 기반]
코어 0 ─ 캐시 ─┐
코어 1 ─ 캐시 ─┼─ 점대점 인터커넥트 ─ 홈 디렉터리
       ···     ┘
```

선의 의미: 합류선은 모든 캐시의 공유 버스 연결 또는 대상 지정 인터커넥트 연결

| 구성요소 | 책임 |
|:---|:---|
| 공유 버스 | **브로드캐스트** 일관성 요청 전달 매체 |
| 스누프 제어기 | 방송 요청 관찰·캐시 라인 상태 전이 |
| **홈 디렉터리** | 블록별 **공유자 목록**·소유자 상태 관리 |
| 점대점 인터커넥트 | 대상 노드에만 일관성 메시지 전달 |

#### 한줄 요약
- 스누핑에서는 매체가 곧 프로토콜이라 공유 버스를 벗어날 수 없고, 디렉터리는 상태를 매체 밖에 두었기에 **점대점 인터커넥트** 위에서 확장할 수 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **무효화 응답(Invalidation Acknowledgement)**: 무효화 요청을 수신한 캐시 노드가 자신의 사본을 Invalid 상태로 전환한 후 요청 노드(또는 홈 노드)로 전송하는 완료 확인 신호.
- **홈 노드(Home Node)**: 특정 메모리 주소 범위의 디렉터리 항목과 물리 DRAM을 물리적으로 소유하고 관리하는 기준 프로세서 노드.

</details>

```text
코어A: 공유 캐시 라인 쓰기 요청
              │
     ┌────────┴─────────────────────┐
     │                              │
[ 1. 버스 스누핑 브로드캐스트 ] [ 2. 디렉터리 기반 선택적 무효화 ]
     │                              │
모든 코어 스누프 제어기 관찰    홈 노드 조회 후 대상 코어 전송
     │                              │
     └─────────┬────────────────────┘
               │
        무효화 응답 수합 후 소유권 확정
               │
        코어A: M 상태로 쓰기 수행
```

분기 결과: 스누핑은 조회 단계가 없어 지연이 짧은 대신 코어 전체가 매번 관여하고, 디렉터리는 **홈 노드** 왕복이 지연에 더해지는 대신 관여 코어를 실제 보유자로 한정

#### 한줄 요약
- **무효화 응답을** 몇 개 기다려야 하는지가 두 방식의 실제 비용이며, 스누핑은 그 수를 미리 알 수 없고 디렉터리는 조회 시점에 확정한다.

## Ⅴ. 종류 및 비교

| 일관성 방식 | 버스 스누핑 | 디렉터리 기반 |
|:---|:---|:---|
| 적용 기준 | 소규모 코어·단일 소켓·공유 버스 가용 | 대규모 코어·다중 소켓·**확장성** 필요 |
| 핵심 특징 | 전체 참여자 요청 관찰·단순 구현 | **공유자 목록** 기반 **선택적 무효화** |
| 한계 | 코어 증가 시 **브로드캐스트** 트래픽 포화 | 디렉터리 저장 공간·홈 노드 조회 지연 |

#### 한줄 요약
- 전환점은 코어 수 자체가 아니라 공유 데이터 비율이며, 코어가 많아도 공유가 거의 없으면 스누프 필터를 붙인 스누핑이 여전히 유효하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 전체 메인 메모리가 아닌 현재 캐시 계층에 적재되어 있는 블록에 대해서만 디렉터리 엔트리를 동적으로 할당하여 메모리 오버헤드를 대폭 절감하는 캐시형 디렉터리 구조.
- **가상 채널(Virtual Channel)**: 단일 물리 링크 내에서 패킷 버퍼를 논리적으로 분리하여 요청 메시지와 응답 메시지 간의 순환 대기 및 프로토콜 교착상태(Deadlock)를 방지하는 인터커넥트 기술.
- **주소 해싱(Address Hashing)**: 메모리 주소 비트열을 해시 함수로 연산하여 디렉터리 홈 노드를 전체 노드에 균등하게 분산시킴으로써 특정 노드로의 트래픽 편중(Hotspot)을 완화하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스누핑 **브로드캐스트가** 코어 증가로 포화 | 계층형 스누핑 또는 디렉터리 방식 전환 | 방송 범위·버스 혼잡 감소 |
| 디렉터리 **공유자 목록** 저장 공간 급증 | **희소 디렉터리**·제한 공유자 수 적용 | 메타데이터 면적 절감 |
| 특정 **홈 노드**에 요청 집중 | **주소 해싱** 기반 홈 노드 분산 | 일관성 지연·핫스팟 완화 |
| 요청·응답 순환으로 인터커넥트 교착 | **가상 채널**·메시지 순서 규칙 적용 | 프로토콜 진행성 확보 |

#### 한줄 요약
- 대책의 방향이 정반대인 이유는 병목의 성격이 달라서이며, 스누핑은 대역폭에서 막히고 디렉터리는 저장 공간과 특정 노드 집중에서 막힌다.

## Ⅶ. 결론

- 소규모 공유 버스는 **버스 스누핑**, 많은 코어·다중 소켓은 **디렉터리 기반 일관성**을 선택하고, 계층형 시스템은 클러스터 내부 스누핑과 상위 디렉터리 병행

#### 한줄 요약
- 실제 대형 시스템이 계층형으로 두 방식을 함께 쓰는 이유는, 한 방식이 이기는 구간이 시스템 안에서도 계층마다 다르기 때문이다.
