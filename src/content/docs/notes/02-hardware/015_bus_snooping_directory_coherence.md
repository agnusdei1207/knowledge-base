## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 공용 공유 버스의 신호를 각 사설 캐시 제어기가 관찰하여 일관성 상태를 파악하는 체계이다.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 각 메모리 주소별 캐시 사본 보유 목록을 중앙 혹은 분산 디렉터리에 기록하여 패킷 전송을 최적화하는 하드웨어 메커니즘이다.
- **선택적 무효화(Selective Invalidation)**: 전체 코어에 트래픽을 방송하지 않고 실제 사본을 보유한 코어에만 점대점 메시지로 무효화 패킷을 전송하는 기술이다.
- **공유자 추적(Sharer Tracking)**: 디렉터리의 메타데이터 표를 이용하여 특정 캐시 라인의 최신 사본을 지닌 코어 목록을 관리하는 방법이다.

</details>

- 정의: 공유 버스의 브로드캐스트를 감시하는 **버스 스누핑**과 주소별 **공유자 추적**을 통해 특정 노드에만 패킷을 전송하는 **디렉터리 기반 일관성** 체계
- 배경: 코어 증설 시 발생하는 전역 스누프 방송의 대역폭 및 전력 소모 병목을 해결하기 위함

#### 한줄 요약

- 소규모 멀티코어의 브로드캐스트 스누핑 한계를 넘어 점대점 전달 방식을 적용한 대규모 시스템의 일관성 구조이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **일관성 순서점(Coherence Ordering Point)**: 동일 메모리 주소에 대한 복수 접근 요청의 글로벌 쓰기 순서를 확정하는 시스템 내 중재 기준점이다.
- **무효화 응답(Invalidation Acknowledgment)**: 무효화 메시지를 수신한 캐시가 사본 파기를 완료하였음을 발신자에게 회신하는 완료 패킷이다.
- **배타적 쓰기 권한(Exclusive Write Permission)**: 다른 코어의 간섭 없이 캐시 라인에 쓰기 연산을 수행할 수 있는 단독 독점 권한이다.
- **방송 관찰(Broadcast Observation)**: 공유 버스를 통과하는 모든 트랜잭션 주소를 칩 내 모든 캐시 제어기가 수신하여 비교하는 동작이다.
- **명단 조회(Directory Lookup)**: 홈 디렉터리에 접근하여 캐시 라인을 보유 중인 코어들의 비트맵 명단을 판독하는 작업이다.

</details>

- 트랜잭션의 전역 순서를 결정짓는 **일관성 순서점**을 구성하여 쓰기 직렬화를 보장함.
- 타 사본들의 **무효화 응답** 수합이 완료된 후에 요청 코어에 **배타적 쓰기 권한**을 부여함.
- 버스 스누핑은 단순한 **방송 관찰**로, 디렉터리 기반은 정밀한 **명단 조회**로 트래픽 전송 대상을 결정함.

#### 한줄 요약

- 일관성 순서점을 통한 요청 직렬화와 무효화 응답 수합을 통해 시스템의 단일 쓰기 소유권을 확정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **버스 중재기(Bus Arbiter)**: 멀티코어 환경에서 공유 매체 접근 요청 간의 우선순위를 할당하는 하드웨어 스케줄러이다.
- **홈 디렉터리(Home Directory)**: 주소 블록의 캐시 보유 목록과 메타데이터를 유지하는 시스템 내 중앙 및 분산 관리 노드이다.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 코어 간 전용 경로를 통해 특정 수신 노드로 일관성 메시지를 직접 라우팅하는 통신망이다.
- **공유 버스(Shared Bus)**: 모든 코어가 단일 신호 선로를 공유하여 주소 트랜잭션을 일시에 전파하는 버스 구조이다.

</details>

```text
[ 버스 스누핑 구조 ]
 +------------+     +------------+     +------------+
 | 코어 0 캐시 |     | 코어 1 캐시 |     | 코어 2 캐시 |
 +------------+     +------------+     +------------+
       │                  │                  │
 ══════╧══════════════════╧══════════════════╧════ [ 공유 버스 브로드캐스트 ]

[ 디렉터리 기반 일관성 구조 ]
 +------------------+     +------------------+
 |    코어 0 노드   |     |    코어 1 노드   |
 +------------------+     +------------------+
          │                        │
 ═════════╧════════════════════════╧══════════════ [ 점대점 인터커넥트 네트워크 ]
          │
 +-------------------------------------------+
 | 홈 디렉터리 노드 (캐시 공유자 비트맵 보유)|
 +-------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| 공유 버스 및 **버스 중재기** | 일관성 트랜잭션 직렬화 및 전 코어 방송 수행 |
| 스누프 제어기 | 방송 버스 감시를 통한 캐시 상태 갱신 제어 |
| **홈 디렉터리** | 주기억장치 주소별 공유자 및 상태 목록 관리 |
| **점대점 인터커넥트** | 대상 노드 간 일관성 제어 메시지의 단독 라우팅 |

#### 한줄 요약

- 스누핑은 버스 중재기와 제어기를 사용하며, 디렉터리 방식은 홈 디렉터리와 점대점 통신망을 결합하여 가동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **홈 노드(Home Node)**: 메모리 주소 번지에 매핑되는 디렉터리 데이터와 물리 메모리를 관장하는 전담 노드이다.
- **공유자 목록(Sharer List)**: 특정 라인을 공유 상태로 읽고 있는 코어들을 식별하기 위한 내부 관리 명단이다.
- **완료 응답 수합(Acknowledgment Collection)**: 홈 노드나 요청 코어가 무효화 대상으로부터 회신 패킷을 빠짐없이 모으는 동기화 절차이다.

</details>

```text
[ 버스 스누핑 흐름 ]
[코어 0 쓰기 요청] ──> 공유 버스 방송 ──> [전체 코어 무효화 수신 및 응답] ──> [쓰기 완결]

[ 디렉터리 기반 흐름 ]
[코어 0 쓰기 요청] ──> [홈 노드 디렉터리 조회 (공유자 코어 2 추출)]
                              │
                              ▼
[특정 대상 점대점 무효화 전송 (코어 2 전송)] ──> [코어 2 완료 응답] ──> [쓰기 완결]
```

### 동작 원리

1. 버스 스누핑 동작: 쓰기 요청을 전체 방송하고 모든 스누프 제어기가 주소 태그를 검사함.
2. 디렉터리 조회: **홈 노드**가 **공유자 목록**을 조회하여 대상 코어를 특정하고 선택적으로 무효화함.
3. 완료 응답 수합: 대상 사본의 **완료 응답 수합**이 끝나면 해당 코어에 배타적 쓰기 권한을 부여함.

#### 한줄 요약

- 스누핑은 방송으로 전체 사본을 폐기하고, 디렉터리 방식은 홈 노드를 통해 파악된 지정 코어에만 점대점 무효화를 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **디렉터리 방식(Directory-Based)**: 별도 저장 공간을 소모하는 대가로 불필요한 트래픽 방송을 억제하는 아키텍처이다.
- **메타데이터(Metadata)**: 디렉터리 메모리에 유지되는 라인별 일관성 상태 및 코어 보유 비트맵 정보이다.
- **다중 소켓(Multi-Socket NUMA)**: 2개 이상의 별도 중앙처리장치 칩이 고속 통신망으로 결합되어 단일 메모리 공간을 형성하는 거대 서버 시스템이다.
- **조회 지연(Lookup Latency)**: 디렉터리에 접근하여 메타데이터를 확인하고 제어 노드를 식별하기까지 추가되는 시간 지연이다.

</details>

| 비교 항목 | 버스 스누핑 방식 | 디렉터리 방식 |
|:---|:---|:---|
| 통신 구조 | **공유 버스** 기반 전체 브로드캐스트 | **점대점 인터커넥트** 기반 직접 전달 |
| 확장성 | 방송 대역폭 포화로 칩 내 코어 증설 한계 | **다중 소켓**까지 계층적인 대규모 확장 용이 |
| 하드웨어 비용 | 추가 메모리 공간이 불필요하여 로직 단순 | **메타데이터** 관리를 위한 추가 저장 공간 소모 |
| 응답 지연 특성 | 공유 버스 중재 지연 및 동시 방송 지연 유발 | **조회 지연** 및 점대점 노드 간 왕복 지연 병합 |

#### 한줄 요약

- 버스 스누핑은 구현 비용과 지연이 적지만 확장성이 떨어지며, 디렉터리 방식은 비용과 지연 증가 대신 스케일아웃에 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 현재 캐시에 적재된 라인의 상태만 디렉터리에 관리하여 용량을 대폭 삭감하는 압축 구조이다.
- **제한 디렉터리(Limited Directory)**: 공유자 기록 개수를 일정 수치 이하로 제한하고 이를 초과할 때만 방송으로 전환하는 타협형 방식이다.
- **주소 해싱(Address Hashing)**: 메모리 주소를 분산하여 특정 디렉터리 노드로 병목 트래픽이 집중되는 현상을 방지하는 기술이다.
- **가상 채널(Virtual Channel)**: 메시지 종류별로 논리적인 전송 채널을 분리하여 통신망 내 교착상태를 방어하는 라우터 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 코어 증가에 따른 디렉터리 **메타데이터** 용량 기하급수적 증가 | **희소 디렉터리** 및 **제한 디렉터리** 방식 도입 적용 | 디렉터리 메모리 오버헤드 축소 및 실리콘 면적 절감 |
| 특정 주소 번지 접근 집중 시 단일 홈 노드로 라우팅 핫스팟 발생 | **주소 해싱** 알고리즘 기반 홈 디렉터리 노드 분산 | 시스템 전체 통신 병목 해소 및 점대점 지연시간 균일화 |
| 요청 패킷과 응답 패킷 충돌로 인한 온칩 네트워크 프로토콜 교착 | 라우터 내부 **가상 채널** 분리 및 메시지 종류별 순서 제어 | 일관성 제어 메시지 교착 완벽 차단 및 시스템 활성 유지 |
| 스누핑 방식에서 한계 코어 초과로 인한 **버스 대역폭** 포화 | 상위 레벨 점대점 전환을 융합한 계층형 스누핑 아키텍처 채택 | 로컬 트래픽 국지화 방어 및 전체 외부 대역폭 확보율 극대화 |

#### 한줄 요약

- 디렉터리 압축, 가상 채널 분리, 계층형 설계를 통해 메타데이터 비용과 대역폭 병목, 통신 교착 상태를 동시에 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **구현 방식 선택 기준(Coherence Architecture Selection Criteria)**: 대상 시스템의 코어 수, 온칩 라우터 구성, 메타데이터 면적 오버헤드를 평가하여 스누핑과 디렉터리 방식을 선택하는 기준이다.

</details>

- 방송 대역폭 소모가 작으면 버스 스누핑을, 대규모 확장성이 필수적이면 디렉터리 방식을 우선 고려함

#### 한줄 요약

- 칩 내부의 트래픽 병목 가능성과 가용 면적 비용을 측정하여 최적의 하드웨어 일관성 아키텍처를 결정해야 한다.
