## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 모든 캐시 제어기가 공유 버스를 지속적으로 감시(Snoop)하여 타 코어의 읽기/쓰기 트랜잭션 발생 시 자신의 캐시 상태를 동기화하는 브로드캐스트 기반 일관성 유지 기법.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 각 메모리 블록의 공유 상태 및 보유 노드 목록(Sharer Mask)을 디렉터리에 기록 관리하고, 변경 시 해당 공유자에게만 점대점으로 유니캐스트/멀티캐스트 메시지를 전송하는 확장형 일관성 기법.
- **브로드캐스트(Broadcast)**: 단일 노드가 발생시킨 메시지나 트랜잭션을 시스템 내의 모든 연결 노드에게 동시에 전파하는 통신 방식.

</details>

- 정의/개념: 공유 버스에 트랜잭션을 방송하여 전수 감시하는 **버스 스누핑(Bus Snooping)**과, 중앙/분산 디렉터리가 사본 보유 노드에만 선택 통지하는 **디렉터리 기반 일관성(Directory-Based Coherence)**
- 배경/필요성: 단일 공유 버스 스누핑만으로는 **코어 수 및 소켓 수 증가($N \ge 8\sim 16$)에 따른 브로드캐스트 트래픽 폭증 및 확장성(Scalability) 한계 극복 불가**

#### 한줄 요약
- 버스 스누핑은 단순성과 저지연을 위해 전수 방송을 사용하고, 디렉터리 방식은 대규모 확장을 위해 사본 보유자에게만 선택 통지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공유자 목록(Sharer List / Bitmask)**: 특정 메모리 블록의 유효 사본을 현재 보유 중인 프로세서 코어 또는 캐시 노드들의 비트맵 목록.
- **선택적 무효화(Selective Invalidation)**: 전체 노드에 방송하지 않고 디렉터리의 공유자 목록에 등재된 특정 캐시 노드에게만 점대점으로 무효화 요청을 전송하는 기법.
- **확장성(Scalability)**: 프로세서 코어 수가 수십~수천 개로 증가해도 인터커넥트 트래픽과 지연시간이 폭증하지 않고 성능이 선형적으로 유지되는 아키텍처 특성.

</details>

- 버스 스누핑: 별도의 디렉터리 저장소 없이 공유 버스 감시만으로 동작하여 구조가 단순하고 소규모 환경에서 최단 지연 보장
- 디렉터리 기반: **공유자 목록(Sharer List)**을 기반으로 **선택적 무효화(Selective Invalidation)**를 수행하여 인터커넥트 트래픽을 최소화하고 높은 **확장성(Scalability)** 달성
- 트레이드오프: 스누핑은 통신 대역폭이 병목이고, 디렉터리는 디렉터리 저장 메모리 오버헤드와 홈 노드 경유 3자 통신 지연(3-Hop Latency)이 수반됨

#### 한줄 요약
- 스누핑은 빠른 대신 대역폭을 많이 쓰고, 디렉터리는 대역폭을 아끼는 대신 홈 노드 경유 지연과 디렉터리 메모리를 소모한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스누프 제어기(Snoop Controller)**: 공유 버스 상의 주소 및 제어 신호를 실시간 스누핑하여 태그 비교 및 로컬 캐시 라인의 상태 전이를 수행하는 하드웨어 제어 로직.
- **홈 디렉터리(Home Directory)**: 특정 물리 메모리 주소 영역의 일관성 상태, 소유자 정보, 공유자 목록을 전담 관리하는 하드웨어 테이블.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 노드 간 직접 연결 또는 라우팅 스위치를 통해 필요한 대상 노드와만 1:1로 통신하는 패킷 기반 고속 인터커넥트망(UPI, Infinity Fabric 등).

</details>

```text
[소규모 단일 소켓: 버스 스누핑 구조]
 ├─ 코어 0 + 사설 캐시 ── [스누프 제어기] ─┐
 ├─ 코어 1 + 사설 캐시 ── [스누프 제어기] ─┼─► [공유 브로드캐스트 버스 (Snooping Bus)] ──► [공유 LLC / DRAM]
 └─ 코어 N + 사설 캐시 ── [스누프 제어기] ─┘

[대규모 다중 소켓: 디렉터리 기반 구조]
 ├─ [노드 0 (소켓 0)] ── 코어 + 사설 캐시 ─┐
 ├─ [노드 1 (소켓 1)] ── 코어 + 사설 캐시 ─┼─► [점대점 패킷 인터커넥트 (UPI/Mesh)] ──► [홈 디렉터리 (Home Node)]
 └─ [노드 N (소켓 N)] ── 코어 + 사설 캐시 ─┘                                                    ├─ 일관성 상태 (M/S/I)
                                                                                               ├─ 소유자 노드 ID
                                                                                               └─ 공유자 비트마스크 (Sharer Mask)
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; 디렉터리는 점대점 패킷 망을 통해 지정된 노드와만 1:1 통신함

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **공유 버스** | 온칩 시스템 버스 | 모든 코어로 일관성 트랜잭션 브로드캐스트 전달 | 스누핑 전용 공통 선로 |
| **스누프 제어기** | 각 코어 캐시 | 방송되는 주소를 감시하여 로컬 캐시 상태 전이 | 전수 태그 비교 수행 |
| **홈 디렉터리** | 메모리 제어기/LLC | 블록별 **공유자 목록** 및 소유자 상태 추적 관리 | 비트마스크 테이블 저장 |
| **점대점 인터커넥트** | 온칩/소켓 간 패킷망 | 요청 노드, 홈 노드, 공유자 노드 간 1:1 유니캐스트 전송 | UPI, CXL, 2D Mesh |

#### 한줄 요약
- 스누핑은 모든 코어가 공유 버스를 매개로 연결되고, 디렉터리는 홈 노드의 비트마스크를 통해 점대점 인터커넥트로 연결된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **홈 노드(Home Node)**: 요청 주소의 물리 메모리와 디렉터리 엔트리를 보유한 기준 노드.
- **요청자 노드(Requester Node)**: 데이터 읽기 또는 쓰기를 요청한 CPU 코어 노드.

</details>

```text
코어 A가 공유 캐시 라인 쓰기(Write) 시도 시 일관성 처리 비교
 ├─ [ 1. 버스 스누핑 방식 (Broadcast) ]
 │    ├─ 2. 공유 버스에 BusRdX (무효화 요청) 브로드캐스트
 │    ├─ 3. 모든 코어의 스누프 제어기가 주소 동시 비교
 │    └─ 4. 타 코어 사본 일괄 무효화(I) 완료 ➔ 코어 A 즉시 쓰기 완료
 │
 └─ [ 2. 디렉터리 기반 방식 (Point-to-Point) ]
      ├─ 5. 코어 A(요청자)가 홈 노드(Home Node)로 쓰기 권한 요청 메시지 전송 (1-Hop)
      ├─ 6. 홈 디렉터리 조회 ➔ 공유자 비트마스크(Sharer Mask) 확인
      ├─ 7. 사본을 보유한 코어 B에게만 선택적 무효화 요청 전송 (2-Hop)
      ├─ 8. 코어 B가 무효화 후 확인 응답(Ack)을 코어 A로 직접 전송 (3-Hop)
      └─ 9. 코어 A가 모든 Ack 수합 후 M 상태로 쓰기 완료
```

분기 결과: **스누핑은** 단 1번의 버스 트랜잭션으로 빠르게 끝나나 전수 대역폭을 소모하며, **디렉터리는** 3-Hop 메시지 교환을 거치나 필요한 노드만 관여함

#### 한줄 요약
- 스누핑은 1번의 방송으로 처리하고, 디렉터리는 요청자 ➔ 홈 노드 ➔ 공유자 ➔ 요청자의 3-Hop 점대점 통신으로 처리한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 버스 스누핑 (Bus Snooping) | 디렉터리 기반 일관성 (Directory-Based) |
|:---|:---|:---|
| 주요 적용 규모 | **소규모 코어 (단일 소켓, 코어 수 $\le$ 8~16개)** | **대규모 다중 소켓, NUMA 서버, 매니코어 ($\ge$ 64개)** |
| 통신 메커니즘 | **공유 버스 기반 브로드캐스트 (전수 방송)** | **점대점 인터커넥트 기반 유니캐스트/멀티캐스트** |
| 확장성 (Scalability) | 낮음 (코어 증가 시 버스 대역폭 포화) | **매우 높음 (필요한 공유자 노드와만 1:1 통신)** |
| 지연시간 (Latency) | 최단 지연 (단일 버스 트랜잭션으로 즉시 완료) | 상대적 지연 증가 (홈 노드 경유 3-Hop 메시지 교환) |
| 하드웨어 오버헤드 | 추가 디렉터리 메모리 불필요 (스누프 로직만 요구) | **디렉터리 저장 메모리(DRAM 용량의 3~10%) 요구** |

#### 한줄 요약
- 단일 칩 소규모 시스템에는 버스 스누핑이, 대규모 다중 소켓 서버 및 NUMA 시스템에는 디렉터리 기반 일관성이 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 전체 메인 메모리가 아닌 현재 캐시 계층에 적재된 블록에 대해서만 디렉터리 엔트리를 동적 할당하는 캐시형 디렉터리 구조.
- **주소 해싱(Address Hashing)**: 메모리 주소를 해시 함수로 분산하여 홈 노드를 전체 소켓에 균등하게 분배함으로써 핫스팟 병목을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 디렉터리 비트마스크 저장으로 인한 메모리 용량 오버헤드 급증 | **희소 디렉터리(Sparse/Coarse Directory)** 구조 적용 | 디렉터리 메모리 점유율을 DRAM의 1% 미만으로 절감 |
| 특정 홈 노드로 메모리 및 디렉터리 요청이 집중되는 핫스팟 현상 | 인터커넥트 **주소 해싱(Interleaved Address Hashing)** 적용 | 소켓 간 트래픽 균등 분산 및 대역폭 포화 방지 |
| 소규모 칩렛 간 통신에서 디렉터리 3-Hop 지연 오버헤드 | **하이브리드 계층형 일관성(칩렛 내 스누핑 + 칩렛 간 디렉터리)** | 로컬 저지연과 글로벌 확장성의 최적 절충 |

#### 한줄 요약
- 실무에서는 희소 디렉터리로 메모리를 아끼고, 주소 해싱으로 핫스팟을 분산하며, 계층형 하이브리드 일관성으로 지연과 확장성을 절충한다.

## Ⅶ. 결론

- 소규모 멀티코어 및 단일 소켓 시스템에는 **저지연 브로드캐스트 기반의 버스 스누핑(Bus Snooping)**을 적용하고, 대규모 NUMA 다중 소켓 및 매니코어 서버 환경에는 **확장성이 뛰어난 점대점 디렉터리 기반 일관성(Directory-Based)**을 채택하며, 최신 칩렛 아키텍처에서는 **로컬 스누핑과 글로벌 디렉터리를 융합한 계층형 하이브리드 일관성**을 구축하는 확장형 고성능 시스템 아키텍처 확립

#### 한줄 요약
- 버스 스누핑은 저지연에, 디렉터리는 대규모 확장에 최적화되어 있으며, 현대 칩렛 시스템은 둘을 결합한 계층형 일관성을 채택한다.
