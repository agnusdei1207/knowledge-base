## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버스 스누핑(Bus Snooping)**: 각 캐시 제어기가 공유 버스의 일관성 트랜잭션을 관찰해 자신의 상태를 갱신하는 방식.
- **디렉터리 기반 일관성(Directory-Based Coherence)**: 메모리 블록별 캐시 보유자 목록을 디렉터리에 기록하고 필요한 노드에만 메시지를 보내는 방식.
- **브로드캐스트(Broadcast)**: 하나의 요청을 모든 일관성 참여자에게 동시에 전달하는 통신 방식.

</details>

- 정의/개념: 버스 트랜잭션 감시(**Snooping**) 또는 중앙 디렉터리의 **공유자 목록 조회**를 통해 캐시 정합성을 유지하는 기법
- 배경/필요성: 대규모 멀티코어 환경에서 공유 버스의 **브로드캐스트 트래픽 포화** 및 확장성 제약 발생

#### 한줄 요약
- 스누핑은 모두에게 물어보고, 디렉터리는 실제 사본을 가진 코어만 찾아 물어보는 일관성 구현 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **공유자 목록(Sharer List)**: 특정 메모리 블록을 캐시에 보유한 코어들의 목록; 디렉터리가 관리.
- **선택적 무효화(Selective Invalidation)**: 공유자 목록에 있는 캐시만 대상으로 사본을 무효화하는 처리.
- **확장성(Scalability)**: 코어 수가 증가해도 통신량과 처리 지연을 감당하며 시스템을 확장하는 성질.

</details>

- 버스 스누핑: 브로드캐스트로 단순하나 코어 증가 시 트래픽 포화
- 디렉터리: 공유자 목록 기반 **선택적 무효화**로 트래픽 절감
- 코어 수와 **확장성** 요구에 따라 방식 선택이 달라짐

#### 한줄 요약
- 참여자가 적으면 전체 방송이 단순하지만, 코어가 많아지면 실제 공유자만 겨냥해 트래픽을 줄여야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스누프 제어기(Snoop Controller)**: 공유 버스에 나타난 요청을 검사하고 자신의 캐시 라인 상태를 전이시키는 회로.
- **홈 디렉터리(Home Directory)**: 메모리 블록의 공유자·소유자 상태를 관리하는 디렉터리 위치.
- **점대점 인터커넥트(Point-to-Point Interconnect)**: 필요한 노드 사이에만 일관성 메시지를 전달하는 연결망.

</details>

```text
[버스 스누핑]
├─ 공유 버스  (브로드캐스트 매체)
└─ 스누프 제어기  (각 코어, 버스 관찰)

[디렉터리 기반]
├─ 홈 디렉터리  (블록별 공유자 목록)
└─ 점대점 인터커넥트  (대상 노드 지정 전송)
```

선의 의미: 가지(`├─`)는 소유 관계; 두 방식은 동일한 캐시 일관성 목표의 대안 구현

| 구성요소 | 책임 |
|:---|:---|
| 공유 버스 | **브로드캐스트** 일관성 요청 전달 매체 |
| 스누프 제어기 | 방송 요청 관찰·캐시 라인 상태 전이 |
| **홈 디렉터리** | 블록별 **공유자 목록**·소유자 상태 관리 |
| 점대점 인터커넥트 | 대상 노드에만 일관성 메시지 전달 |

#### 한줄 요약
- 스누핑은 공유 버스와 관찰 제어기가 핵심이고, 디렉터리는 공유자 정보를 저장할 홈과 대상 전송망이 핵심이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **무효화 응답(Invalidation Acknowledgement)**: 캐시가 사본을 무효화한 뒤 요청자에게 완료를 알리는 응답.
- **홈 노드(Home Node)**: 특정 메모리 주소의 디렉터리 정보를 담당하는 노드.

</details>

```text
코어A: 공유 캐시 라인 쓰기 요청
              │
     ┌────────┴─────────────────────┐
     │                              │
[ 1. 버스 스누핑 브로드캐스트 ] [ 2. 디렉터리 기반 선택적 무효화 ]
     │                              │
모든 코어 스누프 제어기 관찰    홈 노드 조회 후 대상 코어 전송
     │                              │
     └─────────┬────────────────────┘
               │
        무효화 응답 수합 후 소유권 확정
               │
        코어A: M 상태로 쓰기 수행
```

**동작 원리**

1. **버스 스누핑 브로드캐스트**: 모든 코어가 관찰해 해당 사본을 독립 무효화
2. **디렉터리 기반 선택적 무효화**: 홈 노드 조회 후 보유 코어에만 무효화 전송

#### 한줄 요약
- 스누핑은 모든 캐시가 스스로 해당 여부를 판단하고, 디렉터리는 홈 노드가 대상자를 골라 무효화를 진행한다.

## Ⅴ. 종류 및 비교

| 일관성 방식 | 버스 스누핑 | 디렉터리 기반 |
|:---|:---|:---|
| 적용 기준 | 소규모 코어·단일 소켓·공유 버스 가용 | 대규모 코어·다중 소켓·**확장성** 필요 |
| 핵심 특징 | 전체 참여자 요청 관찰·단순 구현 | **공유자 목록** 기반 **선택적 무효화** |
| 한계 | 코어 증가 시 **브로드캐스트** 트래픽 포화 | 디렉터리 저장 공간·홈 노드 조회 지연 |

#### 한줄 요약
- 스누핑은 단순하지만 방송 비용을 지고, 디렉터리는 확장되는 대신 공유자 정보를 저장하고 조회해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **희소 디렉터리(Sparse Directory)**: 실제 캐시된 블록만 디렉터리 엔트리를 할당해 저장 공간을 줄이는 구조.
- **가상 채널(Virtual Channel)**: 요청·응답 메시지를 별도 큐로 분리해 인터커넥트 교착을 방지하는 기법.
- **주소 해싱(Address Hashing)**: 주소를 여러 홈 노드에 분산해 특정 디렉터리 노드 핫스팟을 완화하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스누핑 **브로드캐스트**가 코어 증가로 포화 | 계층형 스누핑 또는 디렉터리 방식 전환 | 방송 범위·버스 혼잡 감소 |
| 디렉터리 **공유자 목록** 저장 공간 급증 | **희소 디렉터리**·제한 공유자 수 적용 | 메타데이터 면적 절감 |
| 특정 **홈 노드**에 요청 집중 | **주소 해싱**으로 홈 노드 분산 | 일관성 지연·핫스팟 완화 |
| 요청·응답 순환으로 인터커넥트 교착 | **가상 채널**·메시지 순서 규칙 적용 | 프로토콜 진행성 확보 |

#### 한줄 요약
- 스누핑은 방송 범위를 줄이고, 디렉터리는 메타데이터와 홈 노드 병목을 줄이는 방향으로 각각 대책을 세운다.

## Ⅶ. 결론

- 소규모 코어는 **버스 스누핑**, 대규모 NUMA 환경은 **디렉터리 기반 일관성** 선택

#### 한줄 요약
- 일관성 방식은 코어 수만 보고 정하지 않고, 모든 코어에 방송할 비용과 공유자 목록을 관리할 비용 중 작은 쪽을 선택한다.
