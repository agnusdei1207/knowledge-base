## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NVLink**: NVIDIA가 개발한 GPU-GPU 및 CPU-GPU 간 전용 고대역폭 직렬 인터커넥트로, 캐시 일관성 및 직접 메모리 공유(P2P)를 제공하는 하드웨어 버스 인터페이스.
- **피어 투 피어 전송(Peer-to-Peer Transfer, P2P 전송)**: 호스트 CPU와 시스템 메인 메모리를 경유하지 않고 가속기 간 전용 버스를 통해 직접 데이터를 송수신하는 메모리 접근 방식.

</details>

- 정의/개념: 호스트 CPU 경유 없이 GPU 간 고대역폭 직접 접근을 지원하는 전용 고속 인터커넥트 **NVLink**
- 배경/필요성: 분산 학습 시 그래디언트 교환 트래픽 급증으로 범용 PCIe 버스 대역폭 포화 및 **통신 지연** 발생

#### 한줄 요약
- 모델이 커질수록 병목이 연산에서 통신으로 옮겨 가므로, 전용 인터커넥트는 성능 옵션이 아니라 규모 확장의 전제 조건이 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NVSwitch**: 단일 노드 내 다수 GPU의 NVLink 포트를 크로스바 스위치 구조로 연결하여 전 대역폭 완전 연결(Full Mesh)을 지원하는 전용 패브릭 스위치 칩.
- **집단 통신(Collective Communication)**: 분산 딥러닝 환경에서 다수 GPU 간 그래디언트 및 텐서 데이터를 동기화하는 다대다 통신 패턴(All-Reduce, All-Gather 등).

</details>

- 다중 링크 집성(Link Aggregation) 기반 범용 PCIe 대비 초고대역폭 제공
- 호스트 메모리 복사 오버헤드를 배제하는 **P2P 전송** 지원
- **NVSwitch** 연동 풀메시 토폴로지로 노드 내 **집단 통신** 경로 극대화

#### 한줄 요약
- 대역폭보다 중요한 것은 어느 GPU 쌍이든 같은 속도로 통신한다는 균일성이며, 이 균일성이 깨지면 가장 느린 경로가 전체 학습 속도를 정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SerDes(Serializer/Deserializer)**: 칩 내부의 병렬 데이터를 초고속 차동 직렬 신호로 변환하여 물리 링크로 송수신하고 복원하는 고속 물리 계층 회로.
- **NCCL(NVIDIA Collective Communications Library)**: 하드웨어 토폴로지를 자동 감지하여 최적화된 링·트리 집단 통신 연산을 실행하는 멀티 GPU 통신 라이브러리.

</details>

```text
[노드 내 스케일업 구조]
├─ GPU 엔드포인트 × 8
│  ├─ HBM (텐서 저장)
│  └─ NVLink 포트·SerDes (직렬 송수신·무손실 패킷 제어)
├─ NVSwitch 패브릭 (논블로킹 크로스바)
├─ NCCL (토폴로지 탐색·집단 통신 스케줄링)
└─ 호스트 CPU·PCIe (부팅·드라이버·스토리지 I/O)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 텐서 트래픽은 NVSwitch 패브릭 안에서 끝나고 호스트 경로는 제어용으로만 남음

| 구성요소 | 책임 |
|:---|:---|
| GPU 엔드포인트 | 텐서 연산·저장과 P2P 패킷 송수신 |
| **SerDes** | 병렬 데이터를 고속 차동 직렬 신호로 상호 변환 |
| NVSwitch 칩 | 다수 GPU 트래픽을 비차단(Non-blocking) 스위칭하여 연결망 확장 |
| **NCCL** | 물리 토폴로지 탐색 기반 링·트리 집단 통신 알고리즘 스케줄링 |
| 호스트 CPU·PCIe | 시스템 부팅, 드라이버 초기화 및 스토리지 I/O 제어 |

#### 한줄 요약
- 구성요소 하나가 소프트웨어라는 점이 핵심이며, 패브릭이 아무리 좋아도 통신 라이브러리가 토폴로지를 잘못 읽으면 대역폭의 일부만 쓰인다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **All-Reduce**: 각 노드/GPU가 계산한 그래디언트를 합산(Reduce)한 뒤, 그 최종 결과를 모든 참여 장치에 동일하게 복제 분배(Broadcast)하는 집단 통신 연산.

</details>

```text
역전파 연산 완료 → 기울기 텐서 확보
        │
   NCCL이 패브릭 토폴로지 탐색
        │
   통신 상대가 같은 노드 안에 있는가?
   ┌────┴─────┐
  예           아니오
   │             │
NVLink P2P로   노드 간 네트워크로 우회
청크 전송         (지연·대역폭 모두 열세)
   │             │
NVSwitch가 목적   │
GPU로 스위칭      │
   │             │
   └────┬────────┘
        │
   전달된 청크를 합산 후 전체에 재분배
        │
   다음 반복 시작
```

분기 결과: 같은 노드 안에서는 전용 링크가 지연을 감춰 주지만 노드 경계를 넘는 순간 대역폭이 한 자릿수 이상 떨어지므로, 병렬화 전략은 통신량이 많은 축을 노드 안에 가두는 방향으로 설계

#### 한줄 요약
- All-Reduce 비용이 GPU 수가 아니라 가장 느린 링크에 좌우되므로, 스케일업 투자는 평균 대역폭이 아니라 최악 경로를 없애는 데 쓰여야 한다.

## Ⅴ. 종류 및 비교

| GPU 인터커넥트 | NVIDIA NVLink | PCIe Gen5 | CXL.mem | InfiniBand (RDMA) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 단일 노드 내 다중 GPU 초고속 스케일업 | 범용 메인보드 기반 일반 확장 카드 연결 | 이기종 메모리 풀링 및 확장 | 노드 간(Scale-out) 대규모 클러스터 네트워킹 |
| 핵심 특징 | GPU 특화 고대역폭 P2P와 NVSwitch | 폭넓은 표준 호환성과 장치 확장 | 호스트-디바이스 캐시 일관성과 메모리 확장 | IB 기반 RDMA와 집단 통신 |
| 한계 | NVIDIA 하드웨어와 시스템 구성에 종속 | GPU 집단 통신에서 대역폭 제약 가능 | GPU 전용 스케일업보다 높은 프로토콜 비용 | 노드 내 전용 링크보다 높은 지연 |

#### 한줄 요약
- 네 인터커넥트는 경쟁 관계가 아니라 거리에 따라 층을 이루므로, 실제 시스템은 하나를 고르는 것이 아니라 어느 계층에 무엇을 둘지를 정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **통신-연산 오버랩(Communication-Computation Overlap)**: 후속 레이어 역전파 연산을 수행하는 동안 선행 레이어 기울기를 비동기로 전송하는 최적화 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 집단 통신 대기로 GPU 연산기 유휴 | **통신-연산 오버랩** 및 텐서 버킷팅 적용 | 통신 지연 은닉으로 분산 학습 처리량 향상 |
| 링크·스위치 오류 시 전체 작업 중단 | 패브릭 링크 상태 감시 및 주기적 체크포인팅 | 결함 링크 신속 격리 및 복구 시간 단축 |
| 고밀도 GPU 노드의 열 포화 | 고효율 수냉 쿨링(Direct-to-Chip) 도입 | 열 스로틀링 방지 및 칩셋 내구성 확보 |
| 다중 노드 확장 시 노드 간 병목 | 노드 내 NVLink, 노드 간 InfiniBand 계층화 | 통신 집중 계층 격리로 확장성 극대화 |

#### 한줄 요약
- 통신을 빠르게 하는 대책보다 통신을 연산 뒤에 감추는 대책이 효과가 큰데, 대역폭은 하드웨어가 정하지만 겹치는 정도는 소프트웨어가 정하기 때문이다.

## Ⅶ. 결론

- 단일 노드는 **NVLink** 및 NVSwitch로 스케일업하고, 노드 간 확장은 **RDMA 패브릭** 기반 계층화

#### 한줄 요약
- 스케일업 투자 판단의 입력은 링크 사양이 아니라 그 모델의 병렬화 방식이 만들어 내는 통신량이며, 이 값을 모른 채 사면 대역폭의 대부분이 남는다.
