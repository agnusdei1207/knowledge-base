## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm TrustZone**: 단일 물리 프로세서 코어, 메모리 계층 및 시스템 버스 인프라를 일반 영역(Normal World)과 보안 영역(Secure World)으로 하드웨어 수준에서 완벽히 격리하는 Arm 보안 확장 아키텍처.
- **신뢰 실행 환경(Trusted Execution Environment, TEE)**: 범용 운영체제(Android, Linux)와 물리적/논리적으로 분리되어 인증, 결제, 암호 키 관리, DRM 등 민감 연산을 안전하게 실행하는 격리 실행 환경.

</details>

- 정의/개념: 단일 실리콘 칩 내부의 연산 코어와 버스를 **Normal World와 Secure World**로 분할하여 **신뢰 실행 환경(TEE)**을 구축하는 **Arm TrustZone 시스템 보안 확장 아키텍처**
- 배경/필요성: 범용 OS(Rich OS)의 거대한 코드 베이스와 취약점으로 인해 **OS가 해킹당하더라도 기밀 암호 키 및 금융/생체인증 데이터 탈취 방지**

#### 한줄 요약
- Arm TrustZone은 시스템 버스 신호 레벨에서 하드웨어 격리를 강제하여 일반 OS가 해킹되어도 Secure World의 암호 자산을 보호한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NS(Non-Secure) 제어 비트**: AXI/AMBA 시스템 버스 트랜잭션 신호선에 하드웨어로 포함되어 현재 메모리/I/O 접근이 보안 영역인지 비보안 영역인지를 칩 레벨에서 판별하는 비트.
- **보안 모니터(Secure Monitor)**: EL3 최고 특권 예외 레벨에서 동작하며, Secure World와 Normal World 간의 하드웨어 레지스터 문맥 전환을 안전하게 중계하는 전용 펌웨어.

</details>

- 버스 레벨 하드웨어 격리: AXI 버스의 **NS(Non-Secure) 비트**를 통해 메모리 컨트롤러와 주변장치가 Normal World의 불법 접근을 하드웨어로 차단
- 안전한 문맥 전환 관문: **보안 모니터(Secure Monitor / EL3)**를 유일한 전환 관문으로 삼아 레지스터 정화(Zeroing) 및 문맥 교환 보장
- 최소 신뢰 코드 베이스(TCB): Secure World에는 필수적인 경량 **신뢰 OS(OP-TEE 등)**와 신뢰 앱(TA)만 상주시체 공격 표면(Attack Surface) 극소화

#### 한줄 요약
- AXI 버스의 NS 제어 비트로 하드웨어 격리를 강제하고, EL3 보안 모니터를 통해 안전하게 문맥을 교환한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TZASC(TrustZone Address Space Controller)**: DRAM 메인 메모리의 특정 주소 범위를 보안 영역과 일반 영역으로 동적 분할 보호하는 하드웨어 컨트롤러.
- **TZPC(TrustZone Protection Controller)**: 타이머, 인터럽트 컨트롤러(GIC), 암호 가속기 등 온칩 주변장치의 보안 속성을 설정하는 하드웨어 모듈.

</details>

```text
[Arm TrustZone 시스템 하드웨어 격리 아키텍처]
 ┌─ [일반 영역 (Normal World - 비신뢰 환경)]       ┌─ [보안 영역 (Secure World - TEE 신뢰 환경)]
 │   ├─ 클라이언트 애플리케이션 (CA)              │   ├─ 신뢰 애플리케이션 (TA: 결제, 생체, 키)
 │   └─ 범용 리치 OS (Android, Linux - EL1)       │   └─ 신뢰 OS (OP-TEE, Trusted OS - S-EL1)
 └──────────────────────┬─────────────────────────┴──────────────────────┬─────────────────────────┘
                        │ (SMC 명령어 트랩)                               │
 ┌──────────────────────▼─────────────────────────────────────────────────▼─────────────────────────┐
 │ [보안 모니터 (Secure Monitor - EL3 최고 특권 레벨)] ── 레지스터 정화 및 안전한 문맥 스위칭       │
 └────────────────────────────────────────┬────────────────────────────────────────────────────────┘
                                          │ AXI 시스템 버스 (NS 비트 신호 제어)
 ┌────────────────────────────────────────▼────────────────────────────────────────────────────────┐
 │ [온칩 시스템 버스 보호 하드웨어]                                                               │
 │   ├─ [TZASC (TrustZone Address Space Controller)] ── DRAM 메모리 영역 보안/비보안 분할 격리     │
 │   └─ [TZPC (TrustZone Protection Controller)] ───── 온칩 암호 엔진 및 주변장치 보안 잠금        │
 └─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 가지(`├─`, `└─`)는 계층 및 하드웨어 보안 경계; SMC 호출 시 EL3 보안 모니터가 문맥을 전환하고, AXI 버스의 NS 비트로 메모리 접근을 통제함

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **일반 영역 (Normal World)**| 비보안 실행단 (EL0/EL1)| 범용 OS 및 대규모 앱 실행 (공격에 노출 가능) | 비신뢰 환경 |
| **보안 영역 (Secure World)**| 신뢰 실행단 (S-EL0/EL1)| 경량 Trusted OS 상에서 **암호 키, 결제 토큰, 생체 정보** 격리 연산 | TEE 환경 |
| **보안 모니터 (EL3)** | 최고 특권 전환 관문 | SMC 호출 처리, **레지스터 정화(Zeroing), 두 World 간 문맥 전환** | 독립 펌웨어 |
| **TZASC 컨트롤러** | 메모리 버스단 | DRAM 주소 공간을 분할하여 Normal World의 보안 메모리 침범 차단 | 하드웨어 주소 필터 |
| **TZPC 컨트롤러** | 주변장치 버스단 | 암호 엔진(AES/RSA), 보안 타이머, GIC 인터럽트 속성 통제 | 온칩 주변장치 잠금 |

#### 한줄 요약
- TrustZone은 Normal World, Secure World, EL3 보안 모니터, TZASC 메모리 컨트롤러 및 TZPC 주변장치 컨트롤러로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SMC(Secure Monitor Call)**: Normal World에서 Secure World의 보안 서비스를 호출하기 위해 하드웨어 트랩을 발생시키는 특권 명령어.

</details>

```text
1. 일반 영역 앱(CA)이 결제 인증 또는 암호 키 서명 요청
                      │
                      ▼
2. 범용 OS 커널이 SMC(Secure Monitor Call) 명령어 실행 ➔ EL3 보안 모니터로 하드웨어 트랩
                      │
                      ▼
3. 보안 모니터: 호출 파라미터 및 호출 권한 유효성 검증
   ┌──────────────────┴──────────────────┐
[ 유효성 검증 실패 (비인가) ]         [ 검증 성공 (정상 호출) ]
   │                                     │
   ▼                                     ▼
오류 코드 반환 후 즉시 복귀           4. Normal World 레지스터 문맥을 안전 메모리에 백업
   │                                     │
   │                                     ▼
   │                                  5. CPU 코어 상태를 Secure World로 절체 ➔ 신뢰 앱(TA) 디스패치
   │                                     │
   │                                     ▼
   │                                  6. TA가 TZASC로 보호된 보안 DRAM 및 하드웨어 암호 엔진으로 연산
   │                                     │
   │                                     ▼
   │                                  7. 연산 결과(토큰/서명)만 비보안 공유 버퍼에 기록
   │                                     │
   │                                     ▼
   │                                  8. 범용 레지스터 잔여 민감 데이터 완전 정화 (Zeroing) ➔ 문맥 복원
   └──────────────────┬──────────────────┘
                      │
                      ▼
9. 일반 영역(Normal World)으로 제어권 복귀 완료
```

분기 결과: **SMC 호출이 승인되면** 보안 모니터를 통해 문맥이 안전하게 전환되어 연산이 수행되며, **연산 후 레지스터가 정화되어** 기밀 누설이 차단됨

#### 한줄 요약
- SMC 호출 ➔ 보안 모니터 검증 ➔ 문맥 저장 ➔ Secure World 진입 ➔ 암호 연산 ➔ 레지스터 정화 ➔ Normal World 복귀 순으로 진행된다.

## Ⅴ. 종류 및 비교

| 하드웨어 보안 격리 기술 | Arm TrustZone | Intel SGX (Software Guard Extensions) | 하이퍼바이저 기반 가상화 격리 | 전용 보안 칩 (TPM / SE) |
|:---|:---|:---|:---|:---|
| 격리 단위 및 범위 | **SoC 전체 시스템 분할 (2개 World)**| 프로세스 내부 특정 엔클레이브 (Enclave) | 가상 머신(VM) 단위 파티셔닝 | 독립된 물리 외장 실리콘 칩 |
| 하드웨어 구현 방식 | **AXI 버스 NS 비트 + TZASC/TZPC** | CPU 내부 메모리 암호화 엔진 (MEE) | CPU 하드웨어 가상화 확장 (VT-x/ARM-VE) | 별도 SPI/I2C 버스 직결 칩셋 |
| 신뢰 코드 베이스 (TCB)| 작음 (경량 Trusted OS) | **매우 작음 (엔클레이브 코드)** | 큼 (하이퍼바이저 전체 코드) | **최소 (독립 보안 OS)** |
| 주요 적용 분야 | **스마트폰, 스마트 TV, 자동차 전장 SoC**| **클라우드 기밀 컴퓨팅 (Confidential)**| 멀티테넌트 퍼블릭 클라우드 서버 | PC 보안 부팅 키 저장, 스마트카드 |

#### 한줄 요약
- 스마트폰 및 임베디드 SoC 전역 보안에는 TrustZone이 표준이며, 클라우드 프로세스 격리에는 SGX가, 외장 키 저장에는 TPM이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TOCTOU(Time-of-Check to Time-of-Use)**: 검사 시점과 실제 사용 시점 사이에 악의적인 일반 OS가 공유 메모리 데이터를 비동기로 바꿔치기하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 버퍼 참조 시 발생하는 **TOCTOU(Time-of-Check to Time-of-Use)** 변조 | **보안 DRAM 내부로 1차 고속 복사 후 파라미터 유효성 검증** | 검사 후 사용 시점 사이의 데이터 위변조 원천 차단 |
| 비보안 DMA 마스터 장치가 보안 메모리에 우회 접근 | **SMMU(System MMU)와 연동하여 장치별 NS 비트 강제 검증** | DMA 우회 경로를 통한 메모리 탈취 차단 |
| 단일 신뢰 앱(TA) 취약점 발생 시 TEE 전체 침해 위험 | **신뢰 앱 간 공간 격리 및 최소 권한(Least Privilege) 원칙** | 특정 TA 손상 시 Secure World 전체 피해 방지 |

#### 한줄 요약
- 실무에서는 보안 메모리 복사로 TOCTOU를 막고, SMMU로 DMA 우회를 차단하며, TA 간 메모리 격리로 안전성을 완성한다.

## Ⅶ. 결론

- 모바일 및 자동차 임베디드 단말의 기밀 데이터와 금융 결제 보안을 위해 **AXI 버스 NS 제어 비트와 TZASC/TZPC를 통합한 Arm TrustZone TEE 아키텍처를 표준 채택**하고, 안전한 시스템 기동을 위해 **하드웨어 RoT 기반 보안 부팅(Secure Boot)**을 연동하며, 통신 구간에서는 **TOCTOU 방지 메모리 격리 설계**를 필수 구현하는 종단 간 임베디드 하드웨어 보안 체계 확립

#### 한줄 요약
- Arm TrustZone은 버스 신호 레벨의 물리적 격리를 통해 일반 OS 침해 시에도 핵심 암호 자산을 보호하는 모바일 보안의 핵심 뼈대다.
