## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **암 트러스트존(Arm TrustZone)**: 스마트폰 칩(AP) 하나를 물리적으로 반으로 쪼개서, 천민들이 노는 '일반 세계'와 귀족들이 숨어있는 '보안 세계'로 완전히 찢어놓는 철통 방어 기술이다.
- **보안 상태(Secure State)**: 삼성페이 지문이나 공인인증서 암호 키처럼 털리면 끝장나는 놈들만 모아놓은, 하드웨어 빗장이 걸린 방탄유리 방(Secure World)이다.
- **비보안 상태(Non-Secure State)**: 안드로이드 OS나 카톡, 게임 앱처럼 언제든 해커한테 털릴 수 있다고 깔고 가는, 방탄유리 바깥의 평범한 흙수저 동네(Normal World)이다.

</details>

- 정의: 하드웨어 칩 자체를 반으로 쪼개서, 절대 뚫리면 안 되는 **보안 상태**(Secure World)와 안드로이드가 도는 **비보안 상태**(Normal World)로 물리적 격리하는 **암 트러스트존**
- 배경: 해커가 안드로이드 폰의 관리자 권한(루팅)을 통째로 탈취하더라도, 삼성페이 지문이나 암호 키만큼은 하드웨어 단에서 끝까지 지켜내기 위함

#### 한줄 요약

- 스마트폰이 해킹(루팅)당해 안드로이드가 털려도, 암호 키와 지문 데이터만큼은 절대로 털리지 않게 칩 안에 하드웨어 방탄유리 방을 하나 더 파놓은 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **엔에스 비트(Non-Secure Bit)**: CPU가 램(RAM)이나 장치를 건드릴 때, 이 놈이 일반 세계 출신(NS=1)인지 보안 세계 출신(NS=0)인지 마빡에 찍어놓은 하드웨어 신분증(완장)이다.
- **공유 버퍼(Shared Buffer)**: 방탄유리를 사이에 두고 바깥 세계(안드로이드)와 안쪽 세계(보안)가 쪽지를 주고받을 수 있도록 허락된 유일한 개구멍(메모리 공간)이다.

</details>

- 프로세서 상태를 절대 뚫리지 않는 **보안 상태**와 언제든 털릴 수 있는 **비보안 상태**로 뼛속까지 시스템 차원 수평 격리함.
- 버스(통신로)에 **엔에스 비트**라는 완장을 채워서, 비보안(NS=1) 영역의 찌끄레기들이 보안(NS=0) 구역의 메모리나 장치를 건드리면 하드웨어가 전기충격으로 차단함.
- 안드로이드(비보안)가 결제 등 보안 서비스를 요청할 때, 정해진 문구멍(**공유 버퍼**)과 검열소(Secure Monitor)를 거치게 하여 도메인 상호 전환을 엄격히 통제함.

#### 한줄 요약

- CPU의 뇌를 일반 모드와 보안 모드로 쪼개고, 버스(데이터 길)에 신분증(NS 비트) 검사기를 달아 일반 놈들이 보안 구역에 얼씬도 못 하게 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **에스엠씨(Secure Monitor Call, SMC)**: 바깥 세계(안드로이드)가 방탄유리 안쪽(보안)에 "문 좀 열어달라"고 두드리는 유일한 노크 명령어이다.
- **티이이(Trusted Execution Environment, TEE)**: 방탄유리 안에서만 굴러가는 쪼그맣고 단단한 보안 전용 운영체제(예: 삼성 녹스 기반 TEE)이다.
- **티씨비(Trusted Computing Base, TCB)**: 시스템이 안 뚫리려면 "얘네들만큼은 무조건 완벽해야 해"라고 믿고 가는 핵심 코드와 하드웨어의 덩어리이다.
- **티지컨트롤러(TZASC/TZPC)**: "이 램(RAM) 1기가는 귀족용, 저 카메라 센서는 천민용"이라고 하드웨어적으로 땅을 쪼개서 못 넘어오게 철조망을 치는 컨트롤러 칩이다.

</details>

```text
[ Arm TrustZone 기반 흙수저(일반) 세계와 귀족(보안) 세계의 뼛속 깊은 물리적 격리 프레임워크 ]
┌──────── 흙수저 비보안 상태 ────────┐     ┌──────── 귀족 보안 상태 ────────┐
│ [ 일반 영역 (안드로이드, 카톡) ]    │     │ [ 티이이(TEE) 방탄유리 구역 ]    │
└─────────────┬────────────────────┘     └───────────────┬────────────────┘
              │ [ 에스엠씨(SMC) 노크 시 모니터 검열소 가동 ] │
              └--------------------------------------------┘
                                     │
                   [ 티지컨트롤러(TZASC) 철조망 (엔에스 비트 검사) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 일반 **비보안 상태** 영역 | 해커가 언제든 뚫을 수 있는 안드로이드나 카카오톡 같은 범용(Rich) OS와 앱들이 뛰노는 무방비 운동장 |
| **에스엠씨** 보안 전환 검열소 | 안드로이드가 보안 영역에 노크할 때, "멈춰!" 하고 몸수색을 하는 문지기 명령어(**에스엠씨**) 및 모니터 |
| 깐깐한 **티이이** 신뢰 실행 구역 | 해킹이 불가능한 방탄유리 안에서 암호 키를 관리하고 지문 인식을 돌리는 초경량 보안 OS(**티이이**) |
| **티지컨트롤러** 하드웨어 철조망 | "이 메모리와 장치는 귀족(보안) 전용이니 천민(일반)이 건드리면 쫓아낸다"고 설정하는 하드웨어 통제 칩 |

#### 한줄 요약

- 안드로이드가 에스엠씨(SMC)로 노크하면, 문지기(Monitor)가 검사하고 문을 열어 방탄유리(TEE) 안의 서비스를 쓰게 해주며, 철조망(TZASC)이 불법 침입을 막는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **시큐어 모니터(Secure Monitor)**: 흙수저 세계와 귀족 세계 사이의 톨게이트를 지키며, 흙수저가 문을 두드리면 무기를 숨겼는지 몸수색하고 들여보내는 최고 권한의 문지기 펌웨어이다.
- **공유 버퍼 검증(Shared-Buffer Validation)**: 안드로이드가 넘겨준 결제 데이터(버퍼 주소)가 폭탄(악성 포인터)인지 아닌지 시큐어 모니터가 샅샅이 뒤지는 폭발물 해체 작업이다.

</details>

```text
[ 안드로이드(비보안)의 결제 요청 시 트러스트존 방탄유리 톨게이트 통과 및 보안 연산 흐름 ]
                               │
                               ▼
    [ 1. 에스엠씨(SMC) 노크: 안드로이드가 지문 결제 요청 시 시큐어 모니터가 파라미터 몸수색 ]
                               │
                               ▼
   [ 2. 엔에스(NS) 비트 통제: CPU가 보안 모드로 변신하고, 하드웨어 버스에서 귀족(NS=0) 완장 참 ]
                               │
                               ▼
   [ 3. 방탄유리(TEE) 내부 연산: 밖으로 유출 안 되는 비밀 키를 꺼내 지문 데이터를 지지고 볶음 ]
                               │
                               ▼
    [ 4. 찌끄레기 반환: "결제 성공했음!" 단답형 영수증만 안드로이드 개구멍으로 던져줌 (키 유출 X) ]
```

### 동작 원리

1. 에스엠씨 출입국 검열: 안드로이드가 지문 결제를 요청(**SMC**)하면, 톨게이트의 **시큐어 모니터**가 파라미터 폭탄(**공유 버퍼 검증**)을 깐깐하게 뒤짐.
2. 엔에스 비트 통제 가동: CPU가 **보안 상태**로 모드를 변신하고, 하드웨어 버스에서 귀족 완장인 **엔에스 비트**(NS=0) 권한을 획득함.
3. 티이이 내부 암호 연산: 방탄유리(**티이이**) 안에서 외부 유출이 절대 안 되는 비밀 키를 꺼내 지문 데이터를 지들끼리 씹고 뜯고 연산함.
4. 비민감 결과만 밖으로 휙: "결제 성공했음!"이라는 단답형 영수증만 개구멍으로 안드로이드로 던져주고, 핵심 키는 절대 방 밖으로 안 빼냄.

#### 한줄 요약

- 안드로이드가 결제를 요청하면 몸수색을 통과한 뒤 방탄유리(TEE) 안에서 몰래 결제를 끝내고, 밖으로는 "성공했다"는 영수증만 던져주어 비밀을 지킨다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **운영체제 권한 격리(OS Privilege Isolation)**: 윈도우나 리눅스가 사용자 앱들끼리 메모리를 못 건드리게 막는 방법인데, 경찰(OS) 자체가 매수당하면(루팅/해킹) 다 털리는 허접한 소프트웨어 방어막이다.

</details>

| 격리 방식 | **암 트러스트존** (하드웨어 뼛속 격리) | **운영체제 권한 격리** (소프트웨어 껍데기 격리) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 삼성페이 암호 키, 지문 정보처럼 폰이 완전히 해킹당해도 무조건 목숨 걸고 지켜야 하는 특급 보안 자산 | 카카오톡과 유튜브 앱끼리 서로 메모리 엿보지 못하게 막는 일반적인 평범한 프로세스 간 링(Ring) 격리 |
| 아키텍처 핵심 구현 특징 | 하드웨어 칩 버스 선에 **엔에스 비트**(NS Bit) 완장을 채워 물리적으로 두 세상을 완전히 찢어놓는 수평 분리 | 운영체제 커널(권력자)이 MMU(메모리 관리자)를 조종해서 앱들을 링(Ring 3) 구석으로 가두는 수직 분리 |
| 극복해야 할 태생적 한계점 | 방탄유리 안의 **티이이**(TEE) 펌웨어나 문지기(**에스엠씨**) 코드 자체가 구멍이 나서 해킹당하면 끝장나는 구조적 취약점 | 스마트폰 루팅(Rooting)으로 안드로이드 커널(경찰)이 통째로 매수당해 털리면 보안이 종잇장처럼 와해되는 끔찍한 한계 |

#### 한줄 요약

- 소프트웨어 격리(운영체제)는 안드로이드가 털리면 끝장이지만, 하드웨어 격리(트러스트존)는 안드로이드가 털려도 물리적인 빗장이 버텨서 안전하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **티씨비 최소화(TCB Minimization)**: 방탄유리(TEE) 안에 앱을 많이 깔수록 해커가 비집고 들어올 쥐구멍이 많아지므로, 지문과 암호 기능 딱 2개만 놔두고 싹 다 쫓아내는 극한의 다이어트이다.
- **경계 취약점(Boundary Vulnerability)**: 안드로이드가 악의적으로 "내 지갑은 메모리 1번지(보안 구역)에 있어"라고 뻥카를 칠 때, TEE가 멍청하게 보안 구역을 덮어써 버리는 기가 막힌 취약점이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 방탄유리(TEE) 안에 쓸데없이 앱을 너무 많이 깔아놔서(TCB 팽창) 해커가 뚫고 들어올 쥐구멍이 많아지는 공격 표면 확대 비상 | 방탄유리 안에는 지문과 암호 키만 남기고 싹 다 쫓아내는 극한의 다이어트(**티씨비 최소화**) 강제 적용 | 방탄유리가 깨질 확률(공격 표면)을 극소화하여 가장 핵심적인 하드웨어 보안 영역 안정성 사수 달성 |
| 안드로이드가 방탄유리 문구멍으로 독극물 포인터(잘못된 메모리 주소)를 밀어 넣어 보안 램을 오염시키는 **경계 취약점** | 문구멍(**공유 버퍼**)으로 들어오는 파라미터 주소가 진짜 안드로이드 구역(NS) 맞는지 뼈와 살을 분리하며 깐깐하게 **공유 버퍼 검증** | 독극물 파라미터 주입으로 인한 Secure World 내부의 핵심 보안 메모리 오염 및 통제권 탈취 완벽 방어 |
| 해커가 CPU 대신 DMA(직접 메모리 접근 칩)를 꼬드겨서 보안 메모리를 몰래 짐수레로 빼돌리는 우회 공격 꼼수 위험 발발 | SMMU와 DMA 컨트롤러 장치에도 **엔에스 비트**(NS) 완장 검열을 똑같이 떡칠하여 하드웨어 접근 원천 통제 | DMA 칩이 미쳐 날뛰며 보안 메모리를 털어가는 하드웨어 우회(Bypass) 탈취 공격 100% 얄짤없이 차단 |

#### 한줄 요약

- 방탄유리(TEE) 안에는 최소한의 기능(TCB 최소화)만 남기고, 밖에서 들어오는 쪽지(공유 버퍼)는 샅샅이 검사하며, DMA 칩이 딴짓 못 하게 NS 비트 완장을 채워라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **보안 격리 지표(Security Isolation Metrics)**: 털렸을 때 그냥 앱이 죽는 수준인지, 은행 계좌가 탈탈 털리는 수준인지 보호 데이터의 치명도를 따져 방탄유리(TrustZone)를 쓸지 말지 정하는 기준표이다.

</details>

- **보안 격리 지표** 원칙에 따라 OS가 뚫려도 지켜야 할 특급 암호 키와 생체 템플릿 코드는 **암 트러스트존**으로, 일반 찌끄레기 프로세스는 **운영체제 권한 격리** 적용으로 통제함

#### 한줄 요약

- 털려도 되는 카톡은 안드로이드(운영체제 격리)에 두고, 절대 털리면 안 되는 삼성페이는 트러스트존(하드웨어 격리)에 숨겨라.
