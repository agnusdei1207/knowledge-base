## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Arm TrustZone**: 프로세서·메모리·버스·주변장치의 접근을 보안과 비보안 상태로 구분하는 Arm 보안 아키텍처.
- **신뢰 실행 환경(TEE, Trusted Execution Environment)**: 일반 실행 환경과 격리해 신뢰 앱과 민감 자산을 처리하는 제한된 실행 환경.

</details>

- 정의/개념: 하나의 프로세서와 버스를 보안·비보안 두 상태로 갈라 **신뢰 실행 환경(TEE, Trusted Execution Environment)** 만드는 **Arm TrustZone** 확장
- 배경/필요성: 범용 OS는 코드 규모가 커 침해를 전제해야 하므로, OS가 뚫려도 키와 인증 연산은 남는 별도 경계가 필요

#### 한줄 요약
- 이 기술의 전제는 일반 OS가 언젠가 뚫린다는 것이며, 방어선을 하나 더 세우는 대신 그 방어선 안쪽을 최대한 작게 유지하는 설계로 이어진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NS(Non-Secure) 비트**: AXI/AMBA 시스템 버스 트랜잭션 신호에 포함되어 현재 접근이 보안 영역인지 비보안 영역인지 하드웨어적으로 판별하는 제어 비트.
- **보안 모니터(Secure Monitor)**: EL3 최고 특권 레벨에서 Secure World와 Normal World 간의 레지스터 문맥 전환을 안전하게 중계하는 펌웨어 계층.

</details>

- 시스템 버스의 **NS(Non-Secure) 비트** 기반 메모리·주변장치 접근을 하드웨어에서 차단
- **보안 모니터(Secure Monitor)** 활용 유일한 출입구로 삼아 두 상태 사이 전환을 통제
- 보안 측 코드량을 최소로 유지해 검증 가능한 범위 안에 공격 표면을 가둠

#### 한줄 요약
- 격리를 소프트웨어 권한이 아니라 버스 신호로 구현했다는 점이 핵심이며, 그래서 상위 소프트웨어를 모두 장악해도 경계 자체는 우회되지 않는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TZASC(TrustZone Address Space Controller)**: DRAM 메인 메모리를 보안 영역과 일반 영역으로 동적 분할 보호하는 하드웨어 컨트롤러.
- **TZPC(TrustZone Protection Controller)**: 타이머, 인터럽트 컨트롤러 등 온칩 주변장치의 보안 속성을 제어하는 모듈.

</details>

```text
[TrustZone 구성]
├─ 일반 영역 (Normal World)
│  ├─ 범용 OS
│  └─ 클라이언트 앱
├─ 보안 모니터 (최고 특권 레벨 · 유일한 전환 통로)
├─ 보안 영역 (Secure World)
│  ├─ Trusted OS
│  └─ 신뢰 앱 (결제·인증·키 관리)
└─ 버스 보호 계층
   ├─ 메모리 격리 제어기 (DRAM 영역 보안 지정)
   └─ 주변장치 제어기 (센서·암호 가속기 잠금)
```

선의 의미: 가지(`├─`)는 소유 관계이며, 두 영역 사이에 직접 연결이 없고 반드시 보안 모니터를 거침

| 구성요소 | 책임 |
|:---|:---|
| 일반 영역 | 범용 OS와 일반 앱이 구동되는 비신뢰 환경 |
| 보안 영역 | 경량 Trusted OS가 키·생체 정보 등 기밀 자산 처리 |
| 보안 모니터 | 전환 시 레지스터 정화와 문맥 교환 수행 |
| **TZASC(TrustZone Address Space Controller)** | DRAM 영역을 보안 전용으로 지정해 일반 접근 차단 |
| **TZPC(TrustZone Protection Controller)** | 온칩 주변장치를 보안 모드 전용으로 잠금 |

#### 한줄 요약
- 보호가 CPU가 아니라 버스 계층에 걸려 있으므로 DMA를 쓰는 장치까지 같은 규칙을 받으며, 이 점이 소프트웨어 격리와 결정적으로 다르다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **클라이언트 앱(CA) & 신뢰 앱(TA)**: Normal World의 일반 앱(Client App)이 Secure World의 전용 보안 서비스(Trusted App)를 호출하는 구조.

</details>

```text
일반 앱이 결제·인증 요청 발생
        │
   보안 서비스 호출 명령으로 최고 특권 계층에 트랩
        │
   보안 모니터가 요청을 허용하는가?
   ┌────┴─────┐
아니오          예
   │             │
오류 반환      일반 영역 문맥 저장 후 보안 영역 진입
   │             │
   │        신뢰 앱이 보호된 장치·키로 연산 수행
   │             │
   │        결과만 공유 버퍼에 기록
   │             │
   │        민감 레지스터 정화 후 문맥 복원
   └────┬────────┘
        │
   일반 OS로 제어 반환
```

분기 결과: 두 영역 사이를 오갈 때마다 문맥 저장과 레지스터 정화가 붙으므로, 전환 비용 때문에 보안 영역은 자주 부르는 기능이 아니라 값진 기능만 담게 됨

#### 한줄 요약
- **클라이언트 앱(CA) & 신뢰 앱(TA)** 사이의 유일한 통로가 공유 버퍼이므로, 보안 검토의 초점도 알고리즘이 아니라 이 버퍼를 다루는 방식에 놓인다.

## Ⅴ. 종류 및 비교

| 하드웨어 보안 격리 기술 | Arm TrustZone | Intel SGX (Enclave) | 하이퍼바이저 가상화 | 하드웨어 보안 칩 (TPM/SE) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 모바일·임베디드·차량용 SoC 전역 보안 | x86 서버 클라우드 기밀 컴퓨팅 | 다중 OS 격리 및 서버 가상화 | 물리적 변조 방지 독립 암호화 모듈 |
| 핵심 특징 | 단일 칩을 2개의 World(Normal/Secure)로 분리 | 프로세스 단위의 암호화 엔클레이브(Enclave) | VM 간 가상 하드웨어 파티셔닝 | 별도의 독립 물리 보안 칩(I2C/SPI 버스) |
| 한계 | Secure World 내부 취약점 시 전체 TEE 장악 | 사이드 채널(Spectre 등) 공격 취약 | 거대한 하이퍼바이저 TCB 및 성능 오버헤드 | 느린 I/O 속도 및 복잡한 연산 처리 불가 |

#### 한줄 요약
- 네 기술은 격리 단위가 상태·프로세스·가상머신·물리 칩으로 갈리며, 단위가 작을수록 보호 범위는 정밀해지고 클수록 우회 경로는 줄어든다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TOCTOU(Time-of-Check to Time-of-Use)**: 검사 시점과 사용 시점 사이에 악성 일반 OS가 공유 메모리 데이터를 바꿔치기하는 취약점.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 버퍼에서 **TOCTOU(Time-of-Check to Time-of-Use)** 발생 | 범위 검증 후 보안 메모리에 복사해 복사본만 사용 | 검사 이후의 값 변경 영향 차단 |
| 비보안 DMA 장치가 보안 메모리에 우회 접근 | 입출력 주소 변환기와 버스 보안 속성을 함께 검증 | 비보안 DMA의 보안 영역 매핑 차단 |
| 보안 영역 내부 취약점 하나로 전체 탈취 | 보안 측 코드 최소화와 신뢰 앱 간 추가 분할 적용 | 단일 신뢰 앱 손상 시 나머지 보호 |
| 부팅 단계 펌웨어 변조로 격리 자체가 무력화 | 하드웨어 신뢰 기점 기반 보안 부팅 연동 | 변조 펌웨어의 실행 차단 |

#### 한줄 요약
- 네 위협 중 셋이 격리 경계를 뚫는 것이 아니라 경계 바깥의 전제를 무너뜨리는 방식이며, 하드웨어 격리의 실제 약점도 늘 그 전제 쪽에 있다.

## Ⅶ. 결론

- 일반 OS가 침해된 뒤에도 키와 인증 연산을 지켜야 하면 TrustZone 기반 신뢰 실행 환경을 보안 부팅과 함께 적용하고, 물리 변조 저항이나 독립된 장애 경계가 더 중요하면 별도 보안 칩과 역할을 나눔

#### 한줄 요약
- 하드웨어가 보장하는 것은 경계의 존재일 뿐 그 안쪽 코드의 품질이 아니므로, 보안 영역이 커지는 순간 이 기술의 이점은 스스로 사라진다.
