## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 계층 구조(Memory Hierarchy)**: 속도·용량·비용이 다른 저장 장치를 계층으로 배치해 지역성을 이용하고 평균 접근 비용을 낮추는 구조.
- **참조 지역성(Locality of Reference)**: 프로그램이 일정 시간 동안 일부 주소를 집중적으로 참조하는 성질; 시간 지역성과 공간 지역성으로 구분.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: 계층별 적중 시간과 미스 비용을 적중률로 가중 합산한 평균 접근 시간.

</details>

- 정의/개념: **참조 지역성**을 이용해 저장 장치를 계층화해 **AMAT**를 최소화하는 구조
- 배경/필요성: 단일 고속·대용량 메모리는 물리적·비용적으로 불가능해 계층 절충 필요

#### 한줄 요약
- 자주 쓰는 데이터는 빠른 작은 저장소에 두고, 덜 쓰는 데이터는 느리지만 큰 저장소에 두어 전체 평균 접근 비용을 낮추는 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시간 지역성(Temporal Locality)**: 최근 사용한 데이터가 가까운 미래에 다시 사용될 가능성이 높은 성질.
- **공간 지역성(Spatial Locality)**: 한 주소를 사용하면 인접 주소도 곧 사용될 가능성이 높은 성질; 캐시 라인 단위 반입 근거.
- **미스 패널티(Miss Penalty)**: 상위 계층에 데이터가 없어 하위 계층에서 가져오는 추가 지연 시간.

</details>

- **시간 지역성**으로 최근 데이터를 상위 계층에 유지해 재사용 적중
- **공간 지역성**으로 인접 블록을 캐시 라인 단위로 반입해 순차 접근 가속
- 계층별 적중률과 **미스 패널티**의 곱이 AMAT를 결정

#### 한줄 요약
- 프로그램의 반복과 순차 접근 패턴을 이용하면, 빠른 계층에 모든 데이터를 담지 않아도 평균적으로 빠르게 동작한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터(Register)**: CPU 내부에서 피연산자와 실행 상태를 가장 빠르게 보관하는 소용량 저장소.
- **캐시(Cache)**: 최근 참조 데이터와 명령어를 프로세서 가까이에 보관하는 SRAM 기반 저지연 저장소.
- **주기억장치(Main Memory)**: 실행 중인 프로그램과 데이터를 보관하는 DRAM 기반 대용량 휘발성 메모리.
- **보조기억장치(Secondary Storage)**: 전원이 꺼져도 파일과 비상주 데이터를 보존하는 SSD·HDD 저장 장치.

</details>

```text
[메모리 계층]  (위 = 빠름·비쌈·소용량 / 아래 = 느림·쌈·대용량)
├─ 레지스터  (~1ns, ~KB)
├─ 캐시 (L1·L2·L3)  (~4ns, ~MB)
├─ 주기억장치 (DRAM)  (~60ns, ~GB)
└─ 보조기억장치 (SSD·HDD)  (~수십μs~ms, ~TB)
```

선의 의미: 가지(`├─`)는 계층 순서; CPU에서 가까울수록 위 계층이며 적중 시 하위 계층 접근 생략

| 구성요소 | 책임 |
|:---|:---|
| 레지스터 | 현재 연산 피연산자·실행 상태 최고속 보관 |
| 캐시 | 반복 참조 블록 저지연 제공·**AMAT** 감소 |
| 주기억장치 | 실행 중 코드·데이터 보관·캐시 미스 공급 |
| 보조기억장치 | 대용량 파일·비상주 데이터 영구 보존 |

#### 한줄 요약
- 위로 갈수록 빠르고 비싸며 작고, 아래로 갈수록 느리지만 싸고 큰 저장소가 계층화된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 라인 리필(Cache Line Refill)**: 하위 계층에서 캐시 라인 크기만큼 데이터 블록을 가져와 상위 계층을 채우는 처리.
- **캐시 적중(Cache Hit)**: 현재 계층에서 요청 데이터를 즉시 찾은 상태.

</details>

```text
CPU 메모리 요청
      │
      ▼
1. 상위 계층(레지스터·L1·L2·L3) 순차 조회
      │
      ├─ 적중 → 데이터 즉시 반환·AMAT 최소
      │
      └─ 미스 → 2. 다음 하위 계층 조회
                      │
               미스 반복 → DRAM → SSD/HDD 순 탐색
                      │
               유효 데이터 발견 → 캐시 라인 리필
                      │
               3. 데이터 반환·상위 계층 갱신
```

**동작 원리**

1. **적중**: 가장 가까운 계층에서 발견 시 즉시 반환; 지역성이 높을수록 상위 계층 적중률 증가
2. **미스**: 하위 계층으로 내려가며 탐색; 각 계층에서 **캐시 라인** 단위로 블록 반입해 상위 계층 리필
3. **반환**: 탐색 완료 후 CPU에 값 반환; 다음 접근을 위해 상위 계층에 블록 유지

#### 한줄 요약
- 가까운 저장소에서 찾으면 즉시 끝나고, 없으면 아래 계층에서 데이터를 가져와 다음 접근을 빠르게 만들며 돌아온다.

## Ⅴ. 종류 및 비교

| 메모리 계층 | 상위 계층 | 하위 계층 |
|:---|:---|:---|
| 적용 기준 | 반복 참조·낮은 지연 우선 | 대용량·낮은 저장 비용 우선 |
| 핵심 특징 | 레지스터·캐시의 저지연·고대역폭 | DRAM·SSD의 대용량·저비용 |
| 한계 | 높은 비트당 비용·소용량 | 높은 접근 지연·대역폭 변동 |

#### 한줄 요약
- 상위 계층은 시간을 아끼고 하위 계층은 공간과 비용을 아끼므로, 둘을 함께 써야 실용적인 시스템이 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 블로킹(Cache Blocking)**: 큰 데이터를 캐시 크기에 맞는 타일로 나누어 반복 재사용을 높이는 소프트웨어 최적화.
- **프리페치(Prefetch)**: 앞으로 사용할 데이터를 미리 상위 계층으로 가져와 **미스 패널티**를 은닉하는 기법.
- **캐시 오염(Cache Pollution)**: 불필요한 데이터가 반입되어 유용한 캐시 라인을 밀어내는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 행렬·텐서가 캐시보다 커 반복 교체 | **캐시 블로킹**으로 작업 타일 구성 | 데이터 재사용·적중률 향상 |
| 순차 비지역성 접근으로 **캐시 오염** | **프리페치** 거리 조정·비지역성 접근 분리 | 오염·대역폭 낭비 감소 |
| DRAM 지연으로 실행 유닛 대기 | 접근 순서 최적화·메모리 병렬성 활용 | 하위 계층 대기 은닉 |
| 대역폭 집중 가속 작업의 공급 부족 | 고대역폭 메모리(HBM) 도입 검토 | 데이터 공급 병목 완화 |

#### 한줄 요약
- 메모리 계층 성능은 하드웨어 크기만의 문제가 아니며, 데이터 접근 순서와 반입 정책을 함께 조정해야 개선된다.

## Ⅶ. 결론

- 반복 접근이 지배적이면 **캐시 블로킹**과 **프리페치**로 **AMAT**를 낮추고, 대역폭 중심 작업은 하위 계층의 전송량과 저장 비용을 기준으로 계층 구성 결정

#### 한줄 요약
- 메모리 계층은 빠른 저장소를 무작정 키우는 설계가 아니라, 프로그램의 지역성과 데이터 전송량에 맞춰 비용을 나누는 설계다.
