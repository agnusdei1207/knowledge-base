## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 계층 구조(Memory Hierarchy)**: 접근 지연시간, 용량, 비트당 비용 격차를 절충하기 위해 레지스터, 캐시, 메인 메모리, 보조기억장치를 피라미드 형태로 배치한 저장 아키텍처.
- **참조 지역성(Locality of Reference)**: 프로그램 실행 중 특정 시점에 특정 메모리 영역을 집중 참조하는 시간적/공간적 패턴.

</details>

- 정의/개념: 프로세서와 메모리 간 속도 격차를 극복하기 위해 참조 지역성(Locality)을 바탕으로 속도, 용량, 비용이 다른 저장장치들을 피라미드 형태로 계층화한 아키텍처
- 배경/필요성: 단일 고속 메모리 구축의 물리적/경제적 한계를 극복하고 **평균 메모리 접근 시간(AMAT)을 최소화하면서 대용량 주소 공간 확보**

#### 한줄 요약

- 참조 지역성을 바탕으로 **상위 고속/소용량과 하위 저속/대용량** 저장장치 계층화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시간 지역성(Temporal Locality)**: 최근 참조된 메모리 주소가 가까운 미래에 다시 참조될 확률이 높은 특성 (루프 변수, 스택).
- **공간 지역성(Spatial Locality)**: 특정 주소가 참조되면 그 인접 주소들이 연속 참조될 확률이 높은 특성 (배열 순회, 순차 명령어).

</details>

- 상위 계층일수록 접근 속도는 극도로 빠르나 비트당 제조 단가가 높아 용량이 제한됨
- **시간 지역성**과 **공간 지역성**을 활용하여 최상위 캐시 계층의 **적중률(Hit Rate)**을 95% 이상으로 유지
- 상위 계층 적중 시간과 하위 계층 **미스 페널티**의 결합을 통한 전체 **평균 메모리 접근 시간(AMAT)** 결정

#### 한줄 요약

- **시간·공간 지역성**을 활용하여 체감 접근 시간을 최상위 캐시 수준으로 수렴

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L1/L2/L3 캐시**: SRAM 기반으로 구성되어 CPU와 메인 메모리 간의 속도 버퍼 역할을 하는 다계층 온칩 캐시.

</details>

```text
[ 메모리 계층 피라미드 아키텍처 ]
          ▲ 속도 극대화 / 고비용 / 소용량 (Sub-ns)
   ┌──────┴──────┐
   │  레지스터   │ (CPU 코어 내부, 수 KB)
   ├─────────────┤
   │ 캐시 메모리 │ (SRAM: L1, L2, L3, 수십 KB ~ 수십 MB)
   ├─────────────┤
   │ 주기억장치  │ (DRAM / HBM: 수 GB ~ 수 TB, 50~80ns)
   ├─────────────┤
   │보조기억장치 │ (SSD / HDD / NVMe: 수 TB ~, 수 us ~ ms)
   └─────────────┘
          ▼ 속도 둔화 / 저비용 / 대용량
```

선의 의미: 레지스터, 캐시(L1/L2/L3), 주기억장치(DRAM), 보조기억장치(SSD/HDD)로 이어지는 피라미드 계층 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 레지스터 | 프로세서 코어 내부에서 피연산자와 연산 상태 즉각 보관 |
| 캐시 메모리 | 최근 사용된 블록의 초저지연 재사용 및 주기억장치 접근 은닉 |
| 주기억장치 | 실행 중인 응용 프로그램 데이터 및 코드의 대용량 저장 제공 |
| 보조기억장치 | 비상주 페이지 데이터 및 파일 시스템의 영구적 비휘발성 보관 |

#### 한줄 요약

- **레지스터 $\to$ 캐시 $\to$ DRAM $\to$ 스토리지**로 이어지는 속도·용량 상호 보완

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 라인 리필(Cache Line Refill)**: 하위 메모리에서 64바이트 블록 단위로 데이터를 가져와 상위 캐시에 적재하는 과정.

</details>

```text
[ CPU 메모리 접근 요청 발생 ]
                │
                ▼
      [ 1. L1 캐시 조회 (Hit / Miss) ]
      ├─ [Hit] ──> 데이터 1클록 즉시 반환
      │
      └─ [Miss] ─> [ 2. L2 / L3 캐시 연쇄 탐색 ]
                        ├─ [Hit] ──> L1 캐시 리필 후 데이터 반환
                        │
                        └─ [Miss] ─> [ 3. DRAM 주기억장치 인출 ]
                                          ├─ [상주] ──> L3/L2/L1 리필 후 반환
                                          │
                                          └─ [비상주] ─> [ 4. SSD Swap-In (Page Fault) ]
```

**동작 원리**

1. **L1 캐시 탐색**: 가장 먼저 L1 캐시를 검색하여 1클록 내 데이터 인출
2. **하위 캐시 탐색**: L1 미스 시 L2, L3 캐시를 순차 탐색하여 캐시 블록(64B)을 상위로 리필
3. **주기억장치 인출**: 모든 캐시 미스 시 통합 메모리 컨트롤러를 통해 DRAM에서 데이터 인출
4. **보조기억장치 적재**: DRAM에도 비상주인 경우 OS 페이지 폴트가 발생하여 SSD에서 스왑 인

#### 한줄 요약

- 상위 계층 미스 시 **하위 계층으로 순차 탐색 및 블록 단위 상위 계층 리필**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Latency vs Bandwidth vs Cost**:
  - 레지스터/L1: Latency 극소화에 집중
  - DRAM/HBM: Bandwidth 및 용량에 집중
  - SSD/HDD: Bit당 Cost 최소화 및 영구 저장에 집중

</details>

| 비교 항목 | 상위 메모리 계층 (SRAM 기반) | 하위 메모리 계층 (DRAM / NAND 기반) |
|:---|:---|:---|
| 적용 기준 | CPU 코어 내부 및 온칩 레벨, 반복 참조 빈도 높은 데이터 | 시스템 메인보드 및 스토리지, 대용량 비상주 데이터 |
| 핵심 특징 | 1~10ns 수준의 극초저지연, 바이트/블록 단위 즉시 하드웨어 접근 | 수백 ns ~ 수 ms 지연, 대규모 블록/페이지 단위 OS 관리 |
| 한계 | 비트당 단가가 매우 높아 수십 MB 이상 대용량 확장 불가 | 물리적 거리에 따른 긴 지연시간으로 인한 파이프라인 정지 위험 |

#### 한줄 요약

- 상위는 **극초저지연 온칩 재사용**, 하위는 **대용량 영구 보존**에 특화

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 블로킹(Cache Blocking / Tiling)**: 큰 행렬 데이터를 L1/L2 캐시 크기에 맞게 작은 타일 블록으로 쪼개어 반복 재사용하는 알고리즘 튜닝.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대용량 행렬 및 텐서 연산 시 캐시 한계 초과로 인한 **반복 교체** 급증 | 프로그램 반복문 재구성을 통한 **캐시 블로킹** 알고리즘 튜닝 적용 | 물리적 캐시 적중률 대폭 향상 및 총 접근 지연 감소 |
| 스트리밍 데이터의 무작위 연속 적재로 인한 치명적인 **캐시 오염** 발생 | 비지역성 메모리 쓰기 명령어 인가 및 하드웨어 **선인출** 강도 제어 | 유용한 작업 집합의 억울한 퇴출 방지 및 오염 차단 |
| 하위 주기억장치의 본질적인 접근 지연(60ns)으로 인한 파이프라인 정지 | 지능형 접근 패턴 분석 기반의 **선인출** 하드웨어 논리 회로 활성화 | 주기억장치 읽기 지연시간을 파이프라인 뒤로 완벽 은닉 |
| 대용량 데이터 셋의 계층 간 이동 시 핀 병목에 따른 전송 대역폭 한계 | 인터포저 기반의 고대역폭 메모리(HBM) 및 3D 적층 기술 적극 도입 | 칩 간 물리적 데이터 이동 병목 해소 및 대역폭 수십 배 확충 |

#### 한줄 요약

- **캐시 블로킹·하드웨어 프리페치·비지역성 힌트·HBM 적층**으로 병목 극복

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL 및 HBM 기반 계층 확장**: 메모리 계층에 HBM(극고대역폭)과 CXL(메모리 풀링 및 확장)이 추가되어 다계층 이종 메모리 아키텍처로 진화.

</details>

- 워크로드 참조 특성 분석 기반 **캐시 블로킹 소프트웨어 튜닝 및 CXL/HBM 기반 차세대 계층 확장**

#### 한줄 요약

- **소프트웨어 지역성 최적화와 이종 메모리(HBM/CXL) 적층**의 결합
