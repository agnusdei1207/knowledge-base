## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 계층 구조(Memory Hierarchy)**: 레지스터, 캐시(L1~L3), 메인 메모리(DRAM), 보조기억장치(SSD/HDD)를 속도, 용량, 비트당 비용에 따라 피라미드형으로 배치하여 참조 지역성을 기반으로 평균 접근 지연시간(AMAT)을 최소화하는 컴퓨터 시스템 구조.
- **참조 지역성(Locality of Reference)**: 프로그램 실행 중 특정 메모리 주소나 인접 주소가 짧은 시간 간격 내에 반복 참조되는 통계적 특성.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: $AMAT = T_{hit} + (Miss\,Rate \times Miss\,Penalty)$로 산출되는 전체 메모리 계층의 유효 접근 시간.

</details>

- 정의/개념: 레지스터, 캐시, 주기억장치, 보조기억장치를 접근 속도와 비트당 비용에 따라 계층적으로 배치하여 **참조 지역성**을 활용해 평균 메모리 접근 시간(AMAT)을 단축하는 **컴퓨터 저장 체계**
- 배경/필요성: 프로세서 연산 속도와 메인 메모리 접근 속도 간의 성능 격차인 **메모리 벽**을 극복하고, 고속 소자의 고비용 한계와 대용량 소자의 저속 한계를 절충하기 위해 도입

#### 한줄 요약
- 메모리 계층 구조는 참조 지역성을 활용하여 레지스터의 초고속 속도와 SSD/HDD의 대용량을 동시에 실현하는 설계 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시간 지역성(Temporal Locality)**: 최근 참조된 메모리 주소가 가까운 미래에 다시 참조될 확률이 높은 특성(반복문, 스택 데이터 등).
- **공간 지역성(Spatial Locality)**: 특정 메모리 주소가 참조될 때 그 인접한 주소들이 연속적으로 참조될 확률이 높은 특성(배열 순회, 순차 코드 실행 등).
- **미스 패널티(Miss Penalty)**: 상위 계층 미스 시 하위 계층에서 데이터를 인출하여 상위 계층을 리필하는 데 소요되는 추가 지연시간.

</details>

- 상위 계층으로 갈수록 초저지연·소용량 특성을 지니며 하위 계층으로 갈수록 **대용량·저비용** 구조를 형성
- 반복 루프의 **시간 지역성**과 순차 블록의 **공간 지역성**을 하드웨어 캐시와 가상 메모리 기법으로 흡수
- 높은 캐시 적중률 유지를 통해 상위 계층 접근 시간 중심의 **유효 AMAT 단축** 달성

#### 한줄 요약
- 상위 계층은 속도를, 하위 계층은 용량을 담당하며, 참조 지역성을 통해 AMAT를 최소화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터(Register)**: CPU 코어 내부 실행 유닛과 직결되어 명령어 피연산자를 최단 1사이클 내에 공급하는 초저지연 임시 저장소.
- **캐시 메모리(Cache Memory)**: SRAM 소자를 활용하여 CPU와 DRAM 간 속도 차이를 완충하는 다단계(L1, L2, L3) 고속 버퍼.
- **메인 메모리(Main Memory)**: 실행 중인 프로세스의 코드와 데이터를 상주시키는 고집적 DRAM 주기억장치.
- **보조기억장치(Secondary Storage)**: 플래시 NAND(SSD) 또는 자기 디스크(HDD) 기반으로 비휘발성 대규모 데이터를 영구 저장하는 저장소.

</details>

```text
+-------------------------------------------------------------+
|               CPU 코어 (Core Execution Units)               |
+-------------------------------------------------------------+
     | 1 사이클 (초저지연, ~0.5ns, 수 KB)
     v
+-------------------------------------------------------------+
|              L1 / L2 / L3 캐시 (SRAM Buffer)                 |
+-------------------------------------------------------------+
     | 수~수십 사이클 (지역성 완충, ~10ns, 수십 MB)
     v
+-------------------------------------------------------------+
|              주기억장치 (DRAM Main Memory)                   |
+-------------------------------------------------------------+
     | 수백 사이클 (물리 적재 공간, ~50-100ns, 수십 GB)
     v
+-------------------------------------------------------------+
|           보조기억장치 (NVMe SSD / NAND Storage)            |
+-------------------------------------------------------------+
     | 수십만~수백만 사이클 (비휘발성 영구 저장, ~수십 us, TB)
     v
+-------------------------------------------------------------+
|               원격 스토리지 및 클라우드 풀                 |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표(`v`)는 상위 초고속 임시 기억 장치에서 하위 대용량 영구 저장 장치로 향하는 계층적 데이터 인출 및 참조 미스 처리 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| **레지스터** | 실행 유닛과 직결되어 1사이클 내에 **피연산자** 즉시 공급 |
| **캐시 메모리** | **참조 지역성**을 활용하여 CPU와 DRAM 사이의 대기 지연 완충 |
| **주기억장치** | 실행 프로세스의 활성 코드와 가상 메모리 페이지를 **DRAM**에 적재 |
| **보조기억장치** | **비휘발성** 대규모 데이터 영구 보관 및 스왑 공간 제공 |

#### 한줄 요약
- 레지스터부터 DRAM까지 위쪽 계층은 모두 바로 아래 계층 접근을 대신하는 사본일 뿐이고 원본을 실제로 보관하는 것은 비휘발성 보조기억장치 하나뿐이므로, 상위 계층은 휘발성을 감수하는 대가로 속도를 얻는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 라인 리필(Cache Line Refill)**: 캐시 미스 발생 시 하위 메모리로부터 64B 블록 전체를 인출하여 상위 캐시에 적재하는 동작.
- **페이지 폴트(Page Fault)**: 가상 주소 참조 시 해당 페이지가 DRAM 물리 메모리에 없어 디스크로부터 적재를 유발하는 인터럽트.

</details>

```text
+-------------------------------------------------------------+
|                CPU 코어 메모리 접근 요청 발행                |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |      L1 캐시 태그 비교        |
               +-------------------------------+
                      |                 |
             [적중]   |                 | [미스]
                      v                 v
+-----------------------+     +-------------------------------+
| 데이터 1사이클 즉시 반환|     |     L2/L3 캐시 순차 조회      |
+-----------------------+     +-------------------------------+
                                        |                 |
                               [적중]   |                 | [미스]
                                        v                 v
                        +-----------------+     +-----------------------+
                        | 데이터 상위 캐시|     |   메인 메모리(DRAM)   |
                        |   리필 후 반환  |     |       페이지 조회     |
                        +-----------------+     +-----------------------+
                                                            |                 |
                                                   [상주]   |                 | [비상주]
                                                            v                 v
                                            +-----------------+     +-----------------------+
                                            | 데이터 캐시 적재|     |  OS 페이지 폴트 처리  |
                                            |   및 CPU 전달   |     | (디스크 스왑 인 발생) |
                                            +-----------------+     +-----------------------+
```

분기 결과: **캐시 적중** 시 1~4사이클 내 초저지연 반환이 보장되나, **페이지 폴트** 발생 시 OS 트랩 및 디스크 I/O가 개입하여 수만 사이클의 지연이 발생함

**동작 원리**

1. **L1 캐시 태그 조회**: CPU가 발행한 가상 또는 물리 주소의 인덱스로 L1 태그를 검색하여 적중 여부를 1사이클 내에 판별함
2. **L2/L3 통합 캐시 탐색**: L1 미스 발생 시 코어 내 L2 및 칩 내부 공유 L3 캐시를 순차 탐색하여 수십 사이클 내 블록 인출을 시도함
3. **DRAM 주기억장치 접근**: 하위 LLC 미스 발생 시 메모리 제어기가 DRAM 행 버퍼를 활성화하여 해당 64바이트 캐시 라인을 물리 메모리에서 인출함
4. **페이지 폴트 예외 처리**: 요구 페이지가 물리 메모리에 없으면 MMU가 페이지 폴트 인터럽트를 발생시키고 운영체제가 디스크 스왑 영역에서 해당 페이지를 DRAM으로 로드함
5. **계층별 역방향 라인 리필**: 하위 저장소에서 획득한 데이터 블록을 상위 캐시 계층으로 순차 복제 적재하면서 CPU 레지스터로 피연산자를 최종 전달함

#### 한줄 요약
- L1에서 SSD까지 계층적으로 탐색하며 미스 발생 시 하위 계층에서 상위 계층으로 라인 리필을 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **포함 캐시(Inclusive Cache)**: 상위 캐시(L1)의 모든 데이터 블록이 하위 캐시(L2/L3)에도 반드시 중복 보관되는 정책.
- **배타적 캐시(Exclusive Cache)**: 동일한 데이터 블록이 L1, L2, L3 중 오직 단 하나의 계층에만 존재하는 정책(전체 유효 용량 극대화).

</details>

| 캐시 포함 정책 | 포함 캐시 (Inclusive) | 배타적 캐시 (Exclusive) |
|:---|:---|:---|
| 적용 기준 | 일관성 검사 트래픽 최소화가 최우선일 때 | 전체 온칩 캐시의 실효 유효 용량 극대화가 필수일 때 |
| 핵심 특징 | 상위 L1/L2 블록을 L3 캐시에도 중복 적재하여 **스누핑 간소화** | L1/L2에서 방출된 블록만 L3에 적재하여 **중복 제거** |
| 한계 | 중복 저장에 따른 가용 **캐시 용량 낭비** | 블록 교체 시 계층 간 이동 및 **제어 로직 복잡도** 증가 |

#### 한줄 요약
- 사설 캐시는 코어의 초저지연을 보장하고, 공유 LLC는 코어 간 공유와 메모리 완충을 담당하며, DRAM은 시스템 전체의 대용량을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 블로킹(Cache Blocking)**: 대규모 데이터 행렬 연산 시 캐시 용량 크기에 맞추어 타일(Tile) 단위로 데이터를 분할 처리하는 알고리즘 최적화 기법.
- **하드웨어 프리페처(Hardware Prefetcher)**: 순차 및 스트라이드 접근 패턴을 감지하여 CPU 요청 전에 메모리 블록을 미리 캐시로 가져오는 유닛.
- **차세대 메모리 기술(Next-Generation Memory Technologies)**: AI 가속 및 대규모 연산의 메모리 벽 극복을 위해 HBM(초고대역폭), CXL(용량 풀링), PIM(인메모리 연산)을 유기적으로 융합한 이기종 메모리 아키텍처.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대규모 행렬 연산 시 캐시 용량 초과로 인한 반복 캐시 스래싱 | **캐시 블로킹**(Tiling) 기법 적용 | 타일 단위 루프 분할을 통해 지역성 극대화 및 DRAM 접근 횟수 대폭 절감 |
| 비순차 데이터 탐색 시 불규칙 지연 및 파이프라인 정체 | **하드웨어 프리페처** 최적화 | 스트라이드 패턴 감지 및 프리페치로 미스 지연시간 은닉 |
| 대규모 AI 워크로드의 폰 노이만 병목 및 메모리 벽 | **차세대 메모리 체계**(HBM·CXL·PIM) 융합 | 3D 적층 초고대역폭 확보 및 호스트 메모리 풀링 실현 |

#### 한줄 요약
- 실무 성능 최적화는 캐시 블로킹 알고리즘, 하드웨어 프리페칭, 차세대 메모리 기술(HBM·CXL·PIM) 도입을 통해 메모리 벽을 극복한다.

- 

#### 한줄 요약
- 메모리 계층 구조는 참조 지역성을 기반으로 성능과 비용의 최적 균형을 달성하는 핵심 설계이며, HBM·CXL·PIM 등 차세대 메모리 기술로 확장 진화하고 있다.
