## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 계층 구조(Memory Hierarchy)**: 속도·용량·비용이 다른 저장 장치를 계층으로 배치해 지역성을 이용하고 평균 접근 비용을 낮추는 구조.
- **참조 지역성(Locality of Reference)**: 프로그램이 일정 시간 동안 일부 주소를 집중적으로 참조하는 성질; 시간 지역성과 공간 지역성으로 구분.
- **평균 메모리 접근 시간(Average Memory Access Time, AMAT)**: 계층별 적중 시간과 미스 비용을 적중률로 가중 합산한 평균 접근 시간.

</details>

- 정의/개념: 속도·용량·비용이 다른 기억장치들을 **참조 지역성**에 따라 피라미드형으로 배치하는 메모리 설계 체계
- 배경/필요성: CPU와 주기억장치의 속도 격차가 세대마다 벌어져, 연산 능력을 늘려도 데이터를 기다리는 시간이 실행 시간을 지배

#### 한줄 요약
- 계층 구조가 성립하는 근거는 하드웨어가 아니라 프로그램의 **참조 지역성**이므로, 지역성이 없는 접근 패턴 앞에서는 어떤 계층 설계도 무력하다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시간 지역성(Temporal Locality)**: 최근 사용한 데이터가 가까운 미래에 다시 사용될 가능성이 높은 성질.
- **공간 지역성(Spatial Locality)**: 한 주소를 사용하면 인접 주소도 곧 사용될 가능성이 높은 성질; 캐시 라인 단위 반입 근거.
- **미스 패널티(Miss Penalty)**: 상위 계층에 데이터가 없어 하위 계층에서 가져오는 추가 지연 시간.

</details>

- **시간 지역성**으로 최근 데이터를 상위 계층에 유지해 재사용 적중
- **공간 지역성**으로 인접 블록을 캐시 라인 단위로 반입해 순차 접근 가속
- 적중 시간에 미스율과 **미스 패널티**의 곱을 더해 AMAT 산출

#### 한줄 요약
- **AMAT** 식에서 미스율은 확률이고 **미스 패널티**는 크기이므로, 계층이 깊어질수록 낮은 확률의 사건이 평균을 지배하는 구조가 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **레지스터(Register)**: CPU 내부에서 피연산자와 실행 상태를 가장 빠르게 보관하는 소용량 저장소.
- **캐시(Cache)**: 최근 참조 데이터와 명령어를 프로세서 가까이에 보관하는 SRAM 기반 저지연 저장소.
- **주기억장치(Main Memory)**: 실행 중인 프로그램과 데이터를 보관하는 DRAM 기반 대용량 휘발성 메모리.
- **보조기억장치(Secondary Storage)**: 전원이 꺼져도 파일과 비상주 데이터를 보존하는 SSD·HDD 저장 장치.

</details>

```text
[메모리 계층]  (위 = 저지연·고비용·소용량)
├─ 레지스터
├─ 캐시 (L1·L2·L3)
├─ 주기억장치 (DRAM)
└─ 보조기억장치 (SSD·HDD)
                 (아래 = 고지연·저비용·대용량)
```

선의 의미: 가지(`├─`)는 계층 순서; CPU에서 가까울수록 위 계층이며 상위 계층 적중 시 하위 계층 접근 생략

| 구성요소 | 책임 |
|:---|:---|
| **레지스터** | 현재 연산 피연산자와 실행 상태를 최고속으로 보관 |
| **캐시** | 반복 참조 블록을 저지연으로 제공해 **AMAT** 감소 |
| **주기억장치** | 실행 중 코드·데이터 보관과 캐시 미스 공급 |
| **보조기억장치** | 대용량 파일과 비상주 데이터의 영구 보존 |

#### 한줄 요약
- 계층 사이 지연 격차가 균등하지 않고 아래로 갈수록 자릿수 단위로 벌어지므로, 한 계층을 놓치는 비용이 계층마다 전혀 다르다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **캐시 라인 리필(Cache Line Refill)**: 하위 계층에서 캐시 라인 크기만큼 데이터 블록을 가져와 상위 계층을 채우는 처리.
- **캐시 적중(Cache Hit)**: 현재 계층에서 요청 데이터를 즉시 찾은 상태.

</details>

```text
CPU 메모리 요청
      │
      ▼
1. 캐시 조회 및 적중 처리
      │
      ├─ 적중 ─────────────→ 데이터 반환
      └─ 미스 → 2. 주기억장치 접근 및 상주 확인
                      │
               ┌──────┴──────┐
             상주            비상주
               │              │
               │       페이지 폴트·저장장치 반입
               └──────┬───────┘
                      │
               3. 캐시 라인 리필 및 반환
```

분기 결과: **캐시 적중**은 상위 계층에서 종료되지만 비상주까지 내려가면 저장장치 지연이 더해져, 같은 한 번의 요청이 나노초 단위와 밀리초 단위로 갈림

#### 한줄 요약
- **캐시 라인 리필**이 요청한 것보다 많은 데이터를 가져오는 이유는 다음 요청을 미리 처리하기 위함이며, 이 도박이 빗나가면 대역폭만 소모된다.

## Ⅴ. 종류 및 비교

| 메모리 계층 | 상위 계층 | 하위 계층 |
|:---|:---|:---|
| 적용 기준 | 반복 참조·낮은 지연 우선 | 대용량·낮은 저장 비용 우선 |
| 핵심 특징 | 레지스터·캐시의 저지연·고대역폭 | DRAM·SSD의 대용량·저비용 |
| 한계 | 높은 비트당 비용·소용량 | 높은 접근 지연·대역폭 변동 |

#### 한줄 요약
- 두 계층은 경쟁하지 않고 서로의 약점을 전제로 설계되므로, 어느 한쪽만으로 시스템을 구성하면 비용이나 성능 중 하나가 즉시 무너진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **캐시 블로킹(Cache Blocking)**: 큰 데이터를 캐시 크기에 맞는 타일로 나누어 반복 재사용을 높이는 소프트웨어 최적화.
- **프리페치(Prefetch)**: 앞으로 사용할 데이터를 미리 상위 계층으로 가져와 **미스 패널티**를 은닉하는 기법.
- **캐시 오염(Cache Pollution)**: 불필요한 데이터가 반입되어 유용한 캐시 라인을 밀어내는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 행렬·텐서가 캐시보다 커 반복 교체 | **캐시 블로킹**으로 작업 타일 구성 | 데이터 재사용·적중률 향상 |
| 스트리밍·비재사용 접근으로 **캐시 오염** | **프리페치** 거리 조정·비재사용 경로 분리 | 오염·대역폭 낭비 감소 |
| DRAM 지연으로 실행 유닛 대기 | 접근 순서 최적화·메모리 병렬성 활용 | 하위 계층 대기 은닉 |
| 대역폭 집중 가속 작업의 공급 부족 | 고대역폭 메모리(HBM) 도입 검토 | 데이터 공급 병목 완화 |

#### 한줄 요약
- **캐시 블로킹**만은 하드웨어를 바꾸지 않고 접근 순서만 바꿔 얻는 이득이라, 같은 코드가 캐시 크기에 따라 몇 배씩 달라지는 원인이 된다.

## Ⅶ. 결론

- 재사용이 높은 작업은 **캐시 블로킹**, 스트리밍 작업은 **프리페치**와 고대역폭 메모리를 적용하되, 캐시 증설에 앞서 **AMAT**와 데이터 이동량 측정으로 병목 계층을 먼저 확정

#### 한줄 요약
- 병목 계층을 확정하지 않은 증설은 거의 항상 빗나가는데, 지역성이 나쁜 프로그램에서는 캐시를 두 배로 늘려도 미스율이 거의 그대로이기 때문이다.
