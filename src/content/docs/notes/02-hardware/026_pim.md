## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PIM(Processing-in-Memory)**: 메모리 뱅크 내부에 연산 유닛(ALU/MAC)을 통합하여 데이터 이동 없이 메모리 내부에서 직접 병렬 처리하는 기술.
- **데이터 이동 병목(Data Movement Bottleneck)**: 프로세서와 메모리 간 대용량 데이터 전송에 소모되는 지연과 에너지가 시스템 성능을 제한하는 현상.
- **연산 오프로딩(Computation Offloading)**: 호스트 CPU/GPU가 수행하던 단순 반복적 대량 연산을 메모리 내장 연산기로 위임하는 제어.

</details>

- 정의/개념: 메모리 셀 또는 뱅크(Bank) 근접 위치에 연산 유닛(ALU/MAC)을 집적하여, 데이터를 프로세서로 전송하지 않고 메모리 내부에서 직접 병렬 연산하는 지능형 반도체 아키텍처
- 배경/필요성: 폰 노이만 구조의 근본 한계인 **데이터 이동 병목(Memory Wall)과 막대한 버스 전송 전력(pJ/bit) 절감 및 AI 벡터 연산 가속**

#### 한줄 요약

- 메모리 내부에서 연산을 직접 수행하여 **데이터 이동 병목과 전력 소모 해소**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 뱅크와 내장 연산기 사이에 형성되는 수 TB/s급의 초광폭 전송 경로.
- **축약 연산(Reduction Operation)**: 대규모 벡터/행렬 데이터를 메모리 내부에서 합산/집계하여 소량의 스칼라 결과만 호스트로 반환하는 연산.

</details>

- 뱅크 단위의 막대한 **내부 대역폭**을 직접 활용하여 외부 메모리 버스 병목 완전 제거
- 원본 데이터 이동 없이 **축약 연산(Reduction)** 결과만 호스트로 반환하여 I/O 전력 소모 대폭 절감
- 메모리 공정의 집적도와 발열 한계를 고려하여 곱셈 누산(MAC) 등 단순 반복형 병렬 연산에 집중

#### 한줄 요약

- **수 테라바이트급 내부 뱅크 대역폭**을 활용하여 데이터 축약(Reduction) 수행

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PIM 연산 유닛(PIM Compute Unit / FPU / MAC)**: DRAM 뱅크마다 1:1 또는 1:2로 결합되어 FP16/INT8 행렬 연산을 수행하는 경량 연산기.
- **내부 축약 버퍼(Reduction Buffer)**: 각 뱅크 연산 유닛들이 산출한 부분 합(Partial Sum)을 모아 최종 합산하는 버퍼.

</details>

```text
[ 메모리 내 연산 (PIM) 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 처리 장치 (Host CPU / GPU : 연산 오프로드 명령 발행) │
└──────────────────────────────┬──────────────────────────────┘
                               │ (명령어 / 주소 오프로드)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 메모리 컨트롤러 및 연산 이관 인터페이스                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ PIM DRAM 칩 다이 배열                                       │
│  ├─ Bank 0 ──> [ PIM Core 0 (MAC) ] ──┐                      │
│  ├─ Bank 1 ──> [ PIM Core 1 (MAC) ] ──┼─> [ 내부 축약 버퍼 ] │
│  ├─ Bank 2 ──> [ PIM Core 2 (MAC) ] ──┤         │            │
│  └─ Bank N ──> [ PIM Core N (MAC) ] ──┘         │            │
└─────────────────────────────────────────────────│───────────┘
                                                  ▼
                                       [ 최종 결과만 호스트 반환 ]
```

선의 의미: 호스트 연산 오프로드 명령부터 뱅크별 PIM 연산 유닛, 내부 축약 버퍼 및 결과 반환 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 연산 이관 인터페이스 | 호스트가 전달하는 특수 연산 명령 및 주소 범위 해독 전달 |
| PIM 연산 유닛 | 뱅크 내부 데이터의 곱셈 누산 등 병렬 연산 직접 수행 |
| 메모리 뱅크 배열 | 원본 데이터를 적재하고 연산기와의 초고속 **내부 대역폭** 제공 |
| 축약 버퍼 | 각 뱅크별로 산출된 부분 결과를 통합하여 최종 집계 수행 |

#### 한줄 요약

- **오프로드 인터페이스·뱅크별 PIM 연산 유닛(MAC)·내부 축약 버퍼** 결합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **부분 결과(Partial Sum)**: 뱅크별 연산 유닛이 로컬 데이터에 대해 계산한 중간 산출물.

</details>

```text
[ 호스트 AI 워크로드 분석 및 PIM 오프로드 판단 ]
                        │
                        ▼
[ 1. PIM 특수 연산 명령어 발행 (FP16 GEMV 등) ]
                        │
                        ▼
[ 2. 뱅크 내부 데이터 초광폭 인출 (Internal Bus) ]
                        │
                        ▼
[ 3. 각 뱅크별 PIM 연산기 병렬 MAC 연산 수행 ]
                        │
                        ▼
[ 4. 연산 결과 내부 축약 (Reduction Tree) ]
                        │
                        ▼
[ 5. 최종 축약 결과만 호스트 버스로 반환 ]
```

**동작 원리**

1. **명령 발송**: 호스트가 PIM 지원 전용 명령어와 메모리 주소 범위를 메모리 컨트롤러로 전송
2. **내부 인출**: 메모리 뱅크에서 TB/s급 내부 버스를 통해 PIM 연산기로 대용량 가중치/벡터 공급
3. **병렬 연산**: 각 뱅크에 직결된 PIM 연산기들이 독립적으로 곱셈 및 누산(MAC) 수행
4. **결과 축약 및 반환**: 내부 축약 버퍼가 부분 합을 취합하여 최종 단일 결과값만 호스트로 전송 완료

#### 한줄 요약

- 호스트 명령 수신 후 **뱅크 내부 인출 $\to$ 병렬 MAC 연산 $\to$ 축약 결과만 반환**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PIM vs Host-Centric**:
  - PIM: 메모리 내부 연산, 높은 축약 비율, 데이터 이동 전력 극소화
  - Host-Centric: 프로세서에서 연산, 복합 제어 로직에 적합, 버스 병목 발생

</details>

| 비교 항목 | 메모리 내 연산 (PIM) | 프로세서 중심 처리 (Host-Centric) |
|:---|:---|:---|
| 적용 기준 | 벡터/행렬 곱셈, AI 임베딩 검색, 높은 축약 비율(Reduction) | 분기문이 복잡한 제어 로직, 데이터 재사용률이 높은 범용 연산 |
| 연산 위치 및 대역폭 | 메모리 뱅크 내부 (내부 수 TB/s 광폭 대역폭 활용) | CPU/GPU 코어 연산기 (외부 버스 대역폭 한계 종속) |
| 한계 및 위험 | 메모리 공정 특성상 복잡한 논리 회로 탑재 곤란, 캐시 일관성 관리 | 데이터 이동에 따른 전력 낭비(Memory Wall) 및 지연 심화 |

#### 한줄 요약

- PIM은 **대량 데이터 축약 및 저전력**, Host-Centric은 **복합 범용 로직 처리** 특화

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Uncacheable Buffer**: 호스트 캐시와 PIM 갱신 데이터 간의 불일치를 방지하기 위해 캐시를 바이패스하는 메모리 매핑.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 캐시 데이터와 갱신 데이터 간의 심각한 캐시 일관성 파괴 | 공유 구역에 **비캐시 버퍼** 할당 및 명시적 강제 동기화 지시어 적용 | 메모리 데이터 정합성 보장 및 구버전 데이터 참조 오류 방지 |
| 호스트가 명령을 발송하고 준비하는 **이관 지연** 발생으로 성능 상쇄 | 대규모 고축약 연산이 확실히 보장되는 워크로드만 선별적으로 이관 | 명령 발송 오버헤드 은닉 및 실질적인 시스템 가속 성능 확보 |
| 특정 메모리 주소가 하나의 뱅크로 쏠려 메모리 내 병렬 연산 무력화 | 뱅크 간 접근을 흩뿌리는 인터리빙 데이터 분산 배치 구조 적극 적용 | 뱅크 유휴 상태 완벽 소거 및 내부 대역폭 100% 한계 가동 |
| 일반 메모리 공정에 논리 연산 회로 혼재 탑재로 인한 발열 급증 및 단가 상승 | 단순한 미세 곱셈 누산기 위주 배치 및 동적 전압 주파수 발열 제어 | 칩 제조 단가 상승 최소 억제 및 발열 통제를 통한 성능 보장 |

#### 한줄 요약

- **Uncacheable 버퍼·오프로드 임계치 선별·뱅크 인터리빙·미세 MAC 구조**로 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **HBM-PIM / CXL-PIM**: 삼성 Aquabolt-XL HBM-PIM 및 CXL 메모리 확장기에 PIM을 탑재하여 대규모 생성형 AI 추론을 가속하는 차세대 솔루션.

</details>

- 데이터 이동 비용이 연산 비용을 압도하는 AI/빅데이터 환경에서 **HBM-PIM, CXL-PIM 기반 도메인 특화 연산 가속**

#### 한줄 요약

- **축약 비율과 데이터 재사용률**을 기준으로 한 호스트-PIM 협력 컴퓨팅 구축
