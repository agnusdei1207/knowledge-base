## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **지능형 반도체 / 메모리 내 연산 (Processing-in-Memory, PIM)**: 메모리 셀 내부(In-Memory) 또는 뱅크(Bank) 근접 유닛 상에 덧셈, 곱셈 누산(MAC) 연산 회로를 내장하여, 데이터를 외부 CPU/GPU로 이동시키지 않고 메모리 내부에서 직접 병렬 연산을 처리하는 지능형 메모리 아키텍처.
- **데이터 이동 병목(Data Movement Bottleneck / Memory Wall)**: 대용량 데이터를 메모리와 연산기 사이로 옮기는 시간•에너지가 연산 효율을 제한하는 현상.
- **연산 이관 (Computation Offloading)**: 호스트 CPU가 수행하던 대규모 단순 반복 병렬 연산(Vector ADD, MAC)을 PIM 메모리 내 내장 연산기로 이관(Offload) 구동하는 제어 동작.

</details>

- 정의/개념: 대용량 데이터의 외부 버스 전송 없이 DRAM 뱅크 내부 셀 및 로직 유닛 상에서 직접 데이터 연산을 실행하는 지능형 메모리 아키텍처 **PIM(Processing-in-Memory)**.
- 배경/필요성: AI 딥러닝 텐서 계산 및 Big Data 스캔 시, 데이터를 호스트 CPU/GPU로 왕복 전송하는 데 따른 **데이터 이동 병목** 및 패키지 핀 전력 소모 폭증 문제를 원천 제거하기 위해 등장.

#### 한줄 요약
- DRAM 뱅크 내부에 연산 회로(ALU/MAC)를 집적하여 원본 데이터의 외부 버스 이동 없이 메모리 내부에서 직접 병렬 연산 및 축약(Reduction)을 완결하는 기술.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 다이 내부의 뱅크와 연산기 간에 형성되는 수 테라바이트(TB/s) 급 칩 내부 전송 경로 대역폭.
- **메모리 내 컴퓨팅(In-Memory Computing, IMC)**: 커패시터 전하 결합이나 저항(ReRAM/PRAM) 등 셀 자체의 신호 합산 물리 현상으로 1클록 내 논리 연산을 완결하는 방식.
- **메모리 근접 처리(Processing-Near-Memory, PNM)**: 뱅크 주변 또는 하단 베이스 로직 다이에 미세 연산기(ALU)를 탑재하여 연산을 처리하는 방식.
- **축약 연산(Reduction Operation)**: 대용량 데이터 배열을 메모리 내부에서 스캔, 필터링, 벡터 덧셈을 구동하여 1개의 최종 결과값으로 줄여 호스트로 돌려주는 고효율 처리.

</details>

- 뱅크 단위의 수 테라바이트(TB/s) 급 **내부 대역폭**을 직접 활용하여 외부 메모리 버스 패키지 병목 해소.
- 원본을 외부 버스로 이동하지 않고 **축약 연산** 결과만 반환하여 I/O 전력과 트래픽 절감.
- 메모리 제작 커패시터 공정 특성의 제약으로 인하여 고복잡도 Out-of-Order 계산보다는 단순 반복형 **MAC(Multiply-Accumulate)** 연산 위주 구동.

#### 한줄 요약
- DRAM 초고속 내부 대역폭 활용 및 Data Reduction 축약 출력을 통해 버스 이동 지연과 전력 소모를 절감함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **연산 이관 인터페이스(Offload Interface / PIM Command Decoder)**: 호스트 CPU가 전달하는 특수 PIM 파이프라인 기계어 명령(PIM_ADD, PIM_MAC 등)을 해석하여 내장 연산기로 발송하는 인터페이스.
- **곱셈 누산 연산기(Multiply-Accumulate Unit, MAC)**: 딥러닝 텐서 가중치(Weight)와 입력값의 곱셈 후 누적 덧셈을 전용 구동하는 미세 연산 로직 유닛.
- **PIM 연산 유닛(PIM Compute Unit / FPU)**: 각 DRAM 뱅크마다 1:1 또는 1:N으로 배치되는 FP16/INT8 정밀도 내장 SIMD 연산기.
- **메모리 뱅크 배열(Memory Bank Array)**: 데이터 원본을 뱅크 단위로 병렬 적재하고 뱅크 내부 데이터 버스를 연산 유닛에 직통 연결하는 저장 공간.

</details>

```text
[ Processing-in-Memory (PIM) Architecture ]
┌───────────────────────────────────────────────────────────┐
│ Host CPU / GPU (Offload Command : PIM_MAC, PIM_REDUCE)   │
├───────────────────────────────────────────────────────────┤
│ PIM Memory Controller / Offload Interface                 │
├───────────────────────────────────────────────────────────┤
│ DRAM Die Array                                            │
│  ├─ Bank 0 ──> [ PIM SIMD / MAC Unit 0 ] ──┐              │
│  ├─ Bank 1 ──> [ PIM SIMD / MAC Unit 1 ] ──┼─> Reduction  │
│  ├─ Bank 2 ──> [ PIM SIMD / MAC Unit 2 ] ──┤   Buffer     │
│  └─ Bank N ──> [ PIM SIMD / MAC Unit N ] ──┘     │        │
└──────────────────────────────────────────────────┼────────┘
                                                   ▼
                                        Return Reduced Result Only
```

| 구성요소 | 책임 |
|:---|:---|
| 연산 이관 인터페이스 | **PIM 명령•주소 범위** 해독•전달 |
| PIM 연산 유닛 | 뱅크 데이터의 **SIMD•MAC 연산** 수행 |
| 메모리 뱅크 배열 | 원본 데이터와 **내부 대역폭** 제공 |
| 축약 버퍼 | 뱅크별 **부분 결과 집계** 수행 |

#### 한줄 요약
- Offload Interface, Bank-level PIM SIMD/MAC Unit 및 Reduction Buffer가 연동하여 내부 병렬 계산을 완결함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **부분 결과(Partial Result)**: 뱅크 단위 PIM 연산 유닛들이 개별 계산하여 출력한 뱅크별 중간 합산 수치.
- **호스트(Host CPU/GPU)**: PIM 전용 라이브러리(PIM API)를 구동하여 뱅크 주소와 PIM 연산자를 메모리로 인출 발송하는 컴퓨팅 모듈.

</details>

```text
[ Host CPU/GPU : PIM Offload Target Workload Identify ]
                         │
                         ▼
        [ 1. 이관 명령 발송 ]
                         │
                         ▼
        [ 2. 뱅크 내부 인출 ]
                         │
                         ▼
        [ 3. 병렬 연산 ]
                         │
                         ▼
        [ 4. 내부 축약 ]
                         │
                         ▼
        [ 5. 결과 반환 ]
```

### 동작 원리

1. **이관 명령 발송**: 호스트가 연산 종류와 주소 범위를 전달함.
2. **뱅크 내부 인출**: 내부 대역폭으로 PIM 유닛에 데이터를 공급함.
3. **병렬 연산**: 뱅크별 유닛이 **Partial Result**를 계산함.
4. **내부 축약**: 축약 버퍼가 부분 결과를 집계함.
5. **결과 반환**: 최종 결과만 호스트에 전달함.

#### 한줄 요약
- Host Command Dispatch -> Bank-internal Read -> PIM MAC Execution -> Internal Reduction -> Result Return 흐름으로 동작함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **축약 비율(Reduction Ratio)**: 연산에 투입된 전체 입력 원본 데이터 대비 최종 출력 데이터 수량의 절감 비율.
- **데이터 재사용(Data Reuse)**: 1번 로드한 데이터를 L1/L2 캐시에 올려두고 반복 계산에 재참조하는 특성.
- **범용 연산(General-Purpose Computation)**: 조건 분기(Branching)가 복잡하고 구조가 일관되지 않은 일반 프로그램 로직.

</details>

| 비교 항목 | PIM 구조 (Processing-in-Memory) | 호스트 중심 처리 구조 (Host-Centric) |
|:---|:---|:---|
| 연산 수행 위치 | DRAM 다이 뱅크 내부 연산기 | 호스트 CPU / GPU 코어 연산기 |
| 데이터 전송 | 외부 이동을 줄이고 결과 중심 반환 | 원본 데이터를 메인 버스로 전송 |
| 주요 적합 워크로드 | **고축약 연산** (Vector ADD, GEMV, Search Scan) | **범용 연산**, 분기문, **데이터 재사용** 연산 |
| 전력 요인 | 외부 I/O 감소, 내부 연산 전력 추가 | 외부 I/O와 호스트 연산 전력 소비 |
| 캐시 일관성 | 호스트 캐시-PIM 간 일관성 제어 필요 | 하드웨어 L1/L2/L3 일관성 자동 유지 |
| 대표 실무 칩 | 삼성 Aquabolt-XL PIM, HBM-PIM, SK하이닉스 AiM | 표준 x86, ARM CPU, NVIDIA GPU |

#### 한줄 요약
- PIM은 단순 대용량 데이터 축약 연산 및 버스 전력 절감에 우수하고, 호스트 중심 처리는 복잡한 범용 연산 및 캐시 재사용에 우수함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 버퍼(Uncacheable Buffer)**: PIM 메모리와 호스트 CPU 간의 캐시 일관성 붕괴(Stale Data)를 방지하기 위해 CPU L1/L2 캐시 적재를 바이패스 시키는 특수 메모리 영역.
- **이관 지연(Offload Latency)**: 호스트가 PIM으로 커맨드를 발송하고 컨텍스트를 세팅하는 데 소요되는 오버헤드 시간.

</details>

| 문제 및 병목 원인 | 실무적 대책 및 해결 방안 | 기대 효과 |
|:---|:---|:---|
| CPU 캐시 데이터와 PIM 갱신 데이터 간의 캐시 일관성 파괴 | 공유 구역에 **비캐시 버퍼** 및 명시적 **Flush** 적용 | 데이터 정합성 보장 및 구버전 데이터 오류 방지 |
| PIM 오프로드 커맨드 세팅 지연(**이관 지연**)이 연산 시간 초과 | 대규모 **고축약 연산** 워크로드만 선별 오프로드 | 오프로드 오버헤드 은닉 및 실질 가속 효과 확보 |
| 특정 주소가 한 뱅크로 쏠려 PIM 내부 병렬성 무력화 | **뱅크 접근 분산** 데이터 인터리빙 배치 | 뱅크 유휴 상태 소거 및 내부 대역폭 100% 가동 |
| DRAM 특수 공정에 연산 회로 탑재로 다이 면적 증가 및 발열 | 단순 16-bit MAC 유닛만 배치하고 DVFS 기반 발열 제어 | 칩 단가 상승 억제 및 지속 가능한 연산 보장 |

#### 한줄 요약
- Uncacheable Buffer 설정(일관성 유지), High-Reduction 연산 선별, Bank Access Interleaving 및 미세 MAC 배치를 적용함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PIM 적용 판단 기준(PIM Adoption Criteria)**: 대상 알고리즘의 데이터 축약 비율(Reduction Ratio), 뱅크 병렬성, 호스트 데이터 재사용률을 평가하여 PIM 오프로드 여부를 결정하는 가이드라인.

</details>

- 축약률•뱅크 병렬성이 높으면 **PIM**, 분기•재사용이 높으면 **Host** 유지.

#### 한줄 요약
- 이동 절감량과 이관•일관성 비용을 비교하여 PIM 적용 범위를 결정함.
