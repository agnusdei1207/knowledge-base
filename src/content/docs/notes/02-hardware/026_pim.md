## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 내 처리(Processing-in-Memory, PIM)**: DRAM 메모리 셀 어레이 또는 내부 뱅크에 연산 유닛을 직접 배치하여 프로세서와 메모리 간의 대규모 데이터 이동을 최소화하는 지능형 컴퓨팅 아키텍처.
- **데이터 이동 병목(Data Movement Bottleneck)**: 폰 노이만 구조에서 프로세서와 외부 메모리 간의 대역폭 한계 및 전송 지연으로 인해 전체 시스템 성능과 에너지 효율이 저하되는 현상.
- **연산 오프로딩(Computation Offloading)**: 호스트 프로세서의 특정 연산 작업을 메모리 내부의 연산 유닛에 위임하여 시스템 버스 트래픽과 호스트 부하를 경감하는 기법.

</details>

- 정의/개념: DRAM 뱅크 또는 로직 계층에 연산기를 직접 집적하여 **데이터 이동 병목**을 해소하는 **PIM**
- 배경/필요성: 원본을 호스트로 반복 전송하는 과정에서 소모하는 대역폭과 에너지가 연산 자체보다 커져 성능을 제한

#### 한줄 요약
- **PIM**은 연산을 빠르게 하려는 기술이 아니라 옮기지 않으려는 기술이며, 데이터 이동이 연산보다 비싸진 시점에야 성립한 발상이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 칩 내부의 뱅크와 연산 유닛 간에 형성된 초광폭 내부 데이터 버스를 통해 제공되는 초고속 전송 대역폭.
- **축약 연산(Reduction)**: 대규모 입력 벡터나 행렬 데이터를 합산·평균·최댓값 탐색 등을 통해 소량의 결과값으로 압축하는 집계 연산.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 두 수의 곱을 계산한 뒤 기존 누적값에 더하는 연산으로, AI 딥러닝 행렬 곱셈 및 디지털 신호 처리의 핵심 기본 연산.

</details>

- **내부 대역폭** 활용으로 메모리 뱅크 데이터를 자체 처리하여 버스 트래픽 절감
- **축약 연산**으로 대량 원본 대신 소량 부분 결과만 호스트로 반환
- **MAC** 병렬 처리로 AI 추론의 행렬·벡터 연산을 오프로딩

#### 한줄 요약
- 이득은 입력 대비 출력이 얼마나 작아지느냐에 정확히 비례하므로, **축약 연산** 성격이 없는 작업은 PIM에 올려도 얻을 것이 없다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PIM 연산 유닛(PIM Compute Unit)**: 메모리 뱅크 옆에 집적되어 뱅크로부터 직접 인출한 데이터에 대해 산술·논리 연산을 병렬로 실행하는 소형 연산기.
- **부분 결과(Partial Sum)**: 각 독립 뱅크의 PIM 연산 유닛이 로컬 데이터에 대해 개별 계산을 수행하여 산출한 중간 결과값.
- **축약 버퍼(Reduction Buffer)**: 다수 뱅크에서 생성된 부분 결과를 취합하여 최종 축약 연산을 수행하고 결과를 임시 보관하는 하드웨어 버퍼.

</details>

```text
[호스트 CPU·GPU] ── [오프로딩 인터페이스] ── [메모리 뱅크 군]
                                               ├─ 뱅크 0 ─ PIM 연산 유닛
                                               ├─ 뱅크 1 ─ PIM 연산 유닛
                                               └─ 축약 버퍼
```

선의 의미: `──`는 연산 지시·결과 경로, 가지는 뱅크별 데이터와 근접 연산 유닛의 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU·GPU | **연산 오프로딩** 요청 발행과 최종 결과 소비 |
| 오프로딩 인터페이스 | 연산 종류·대상 주소 범위 전달 |
| 메모리 뱅크 | 원본 데이터 저장·**내부 대역폭** 제공 |
| **PIM 연산 유닛** | 뱅크 근처 데이터의 **MAC** 병렬 처리 |
| **축약 버퍼** | 뱅크별 **부분 결과** 결합·최종 결과 보관 |

#### 한줄 요약
- 연산기가 DRAM 공정으로 만들어진다는 제약이 구조 전체를 규정해, 뱅크 옆에 놓을 수 있는 것은 단순 산술기뿐이고 복잡한 제어는 애초에 들어갈 수 없다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **뱅크 인터리빙(Bank Interleaving)**: 연속된 메모리 주소를 여러 물리 뱅크에 교차 배치하여 다수 뱅크를 동시 병렬 접근할 수 있도록 하는 기법.
- **호스트 버스(Host Bus)**: 호스트 프로세서와 메모리 서브시스템 간에 제어 명령, 주소, 최종 데이터를 주고받는 시스템 외부 인터페이스 버스.

</details>

```text
호스트: PIM 연산 요청 (연산 종류·주소 범위)
      │
      ▼
1. 주소 분할 및 뱅크 요청 분배: 대상 주소를 여러 뱅크 요청으로 분할
      │
      ▼
2. 뱅크별 PIM 로컬 병렬 처리: 내부 대역폭으로 직접 연산
      │
      ▼
3. 축약 버퍼 결합 및 반환: 부분 결과 결합 후 호스트 버스 전송
```

분기 결과: 데이터가 여러 뱅크에 흩어져 있으면 **뱅크 인터리빙** 덕에 연산이 병렬로 진행되지만, 한 뱅크에 몰려 있으면 내부 대역폭이 있어도 직렬화되어 **호스트 버스** 전송과 다를 바 없어짐

#### 한줄 요약
- 성능이 데이터 배치에 전적으로 달려 있어 같은 연산도 저장 방식에 따라 이득이 사라지므로, PIM 도입은 하드웨어 교체가 아니라 자료구조 재설계에 가깝다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일관성 유지(Coherence Maintenance)**: 호스트 CPU 캐시에 저장된 데이터 사본과 PIM 메모리 내부의 데이터가 서로 불일치하지 않도록 동기화하는 하드웨어 및 소프트웨어 제어 기법.

</details>

| 처리 방식 | PIM | 호스트 중심 처리 |
|:---|:---|:---|
| 적용 기준 | 규칙적 대량 데이터·원본보다 작은 결과 | 복합 제어·다양한 범용 연산 |
| 핵심 특징 | **내부 대역폭** 활용·버스 트래픽 감소 | CPU·GPU 실행 유닛의 유연한 연산 |
| 한계 | 지원 연산 제한과 **일관성 유지** 비용·내부 발열 | 데이터 이동 지연과 전력 증가 |

#### 한줄 요약
- 둘은 대체 관계가 아니라 한 프로그램 안에서 구간별로 갈리므로, 실제 판단 단위는 시스템이 아니라 커널 하나하나가 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 매핑(Uncacheable Mapping)**: PIM이 수정할 메모리 영역을 호스트 CPU의 캐시에 적재되지 않도록 메모리 속성을 비캐시(Uncacheable)로 설정하여 데이터 불일치를 원천 방지하는 기법.
- **뱅크 충돌(Bank Conflict)**: 복수의 연산 요청이나 주소 접근이 동일한 물리 뱅크에 동시에 집중되어 내부 병렬 처리가 직렬화되고 지연이 발생하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 캐시와 PIM 데이터 불일치 | **비캐시 매핑** 또는 캐시 정리·무효화 | 최신 데이터 관찰 일치 |
| 연산 요청이 한 뱅크에 집중해 **뱅크 충돌** | **뱅크 인터리빙**·데이터 재배치 | 내부 병렬성 향상 |
| 오프로딩 준비 비용이 결과 이득 상쇄 | 원본 대비 결과가 작은 연산만 이관 | 명령·데이터 이동 비용 회수 |
| 메모리 내부 연산기 발열 증가 | 단순 연산 중심 배치·전력 제어 | 열 한도 내 처리량 유지 |

#### 한줄 요약
- 캐시를 우회하는 순간 하드웨어가 대신해 주던 일관성 관리가 소프트웨어 책임으로 넘어오며, 이 비용이 PIM 도입 실패의 가장 흔한 원인이다.

## Ⅶ. 결론

- 원본 대비 결과가 작고 연산이 규칙적이면 **PIM**에 선택적으로 오프로딩하고, 복잡한 제어와 공유 상태는 호스트 처리로 유지해 PIM을 범용 프로세서의 보완 계층으로 운용

#### 한줄 요약
- 계산 가능 여부는 진입 조건일 뿐이고 실제 판정은 축약률 대 동기화 비용의 대소 비교이며, 이 비교는 워크로드마다 다시 해야 한다.
