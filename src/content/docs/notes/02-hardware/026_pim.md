## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 내 연산(Processing-in-Memory)**: 메모리 셀 내부나 뱅크 근접 위치에 연산 회로를 내장하여, 데이터를 프로세서로 옮기지 않고 메모리 안에서 직접 병렬 연산하는 지능형 아키텍처이다.
- **데이터 이동 병목(Data Movement Bottleneck)**: 대용량 데이터를 메모리와 프로세서 사이로 왕복시키는 데 소모되는 시간과 에너지가 전체 연산 효율을 갉아먹는 치명적인 현상이다.
- **연산 이관(Computation Offloading)**: 중앙처리장치가 수행하던 단순 반복적 병렬 연산을 메모리에 내장된 연산기로 위임하여 구동하는 제어 기법이다.

</details>

- 정의: 데이터를 외부로 이동시키지 않고 메모리 내부에서 직접 병렬 연산을 처리하는 지능형 메모리 아키텍처
- 배경: 대용량 데이터 연산 시 발생하는 심각한 **데이터 이동 병목**과 막대한 핀 전력 소모 문제를 근본적으로 해결하기 위함

#### 한줄 요약

- 메모리 내부에 연산기를 집적하여 원본 데이터의 외부 버스 왕복 없이 내부에서 병렬 연산과 축약을 완결하는 차세대 반도체 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 칩 내부의 뱅크와 연산기 간에 형성되는 수 테라바이트급의 막강한 데이터 전송 경로 대역폭이다.
- **메모리 내 컴퓨팅(In-Memory Computing)**: 커패시터나 저항 등 셀 자체의 물리 현상을 이용하여 1클록 내에 아날로그적 논리 연산을 완결하는 방식이다.
- **메모리 근접 처리(Processing-Near-Memory)**: 뱅크 주변이나 하단 로직 다이에 미세 연산기를 탑재하여 데이터를 최단 거리에서 처리하는 방식이다.
- **축약 연산(Reduction Operation)**: 대용량 데이터를 메모리 내부에서 스캔 및 덧셈하여 하나의 최종 결과값으로 압축한 뒤 호스트로 돌려주는 고효율 연산이다.

</details>

- 뱅크 단위의 막대한 **내부 대역폭**을 활용하여 외부 메모리 버스 병목을 하드웨어적으로 완전히 해소함.
- 원본 데이터 이동 없이 **축약 연산** 결과만 반환하여 입출력 트래픽과 패키지 전력 소모를 대폭 절감함.
- 메모리 공정의 제약으로 복잡한 연산보다는 곱셈 누산 등 단순 반복형 병렬 연산을 위주로 구동함.

#### 한줄 요약

- 막강한 메모리 내부 대역폭을 연산기에 직접 공급하고 데이터 축약을 통해 외부 인터페이스의 지연과 전력 낭비를 차단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **연산 이관 인터페이스(Offload Interface)**: 호스트가 전달하는 파이프라인 기계어 명령을 해석하여 내장 연산기로 발송하는 제어 접점이다.
- **곱셈 누산 연산기(Multiply-Accumulate Unit)**: 가중치와 입력값의 곱셈 후 누적 덧셈을 전용으로 구동하는 텐서 처리에 특화된 미세 연산 로직이다.
- **PIM 연산 유닛(PIM Compute Unit)**: 각 메모리 뱅크마다 1대 1 또는 1대 다수로 배치되는 정밀도 내장 병렬 연산기이다.
- **메모리 뱅크 배열(Memory Bank Array)**: 데이터 원본을 뱅크 단위로 병렬 적재하고 뱅크 내부 데이터 버스를 연산 유닛에 직통으로 연결하는 저장 공간이다.

</details>

```text
[ 메모리 내 연산 (PIM) 아키텍처 ]
+-------------------------------------------------------------+
| 호스트 처리 장치 (연산 이관 명령 및 주소 범위 발송)         |
+-------------------------------------------------------------+
                              │
                              ▼
+-------------------------------------------------------------+
| 메모리 제어기 및 연산 이관 인터페이스                       |
+-------------------------------------------------------------+
                              │
+-------------------------------------------------------------+
| 메모리 칩 다이 배열                                         |
|  ├─ 뱅크 0 ──> [ 연산 유닛 0 ] ──┐                          |
|  ├─ 뱅크 1 ──> [ 연산 유닛 1 ] ──┼─> [ 내부 축약 버퍼 ]     |
|  ├─ 뱅크 2 ──> [ 연산 유닛 2 ] ──┤           │              |
|  └─ 뱅크 N ──> [ 연산 유닛 N ] ──┘           │              |
+----------------------------------------------│--------------+
                                               ▼
                                      [ 최종 결과만 반환 ]
```

| 구성요소 | 책임 |
|:---|:---|
| **연산 이관 인터페이스** | 호스트가 전달하는 특수 연산 명령 및 주소 범위 해독 전달 |
| **PIM 연산 유닛** | 뱅크 내부 데이터의 곱셈 누산 등 병렬 연산 직접 수행 |
| **메모리 뱅크 배열** | 원본 데이터를 적재하고 연산기와의 초고속 **내부 대역폭** 제공 |
| 축약 버퍼 | 각 뱅크별로 산출된 부분 결과를 통합하여 최종 집계 수행 |

#### 한줄 요약

- 이관 인터페이스를 통해 명령을 수신하고, 뱅크별 연산 유닛이 병렬 연산을 수행한 뒤 축약 버퍼를 거쳐 결과만 반환한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **부분 결과(Partial Result)**: 뱅크 단위 연산 유닛들이 개별적으로 계산하여 출력한 뱅크별 중간 합산 수치이다.
- **호스트(Host)**: 전용 라이브러리를 구동하여 대상 주소와 연산 명령을 식별한 후 메모리로 인출 발송하는 컴퓨팅 모듈이다.

</details>

```text
[ 호스트 인공지능 워크로드 식별 및 분석 ]
                 │
                 ▼
       [ 1. 연산 이관 명령 발송 ]
                 │
                 ▼
       [ 2. 뱅크 내부 데이터 인출 ]
                 │
                 ▼
       [ 3. 각 뱅크별 병렬 연산 ]
                 │
                 ▼
       [ 4. 연산 결과 내부 축약 ]
                 │
                 ▼
         [ 5. 최종 결과 반환 ]
```

### 동작 원리

1. 이관 명령 발송: **호스트**가 연산 종류와 주소 범위를 인터페이스로 전달함.
2. 뱅크 내부 인출: 막대한 내부 대역폭으로 뱅크의 데이터를 **PIM 연산 유닛**에 공급함.
3. 병렬 연산: 뱅크별 연산 유닛이 **부분 결과**를 병렬로 동시 계산함.
4. 내부 축약: 축약 버퍼가 모든 뱅크의 부분 결과를 하나의 최종값으로 집계함.
5. 결과 반환: 도출된 압축된 최종 결과값만 외부 버스를 통해 호스트로 즉각 반환함.

#### 한줄 요약

- 호스트의 명령에 따라 내부에서 데이터를 읽고 병렬 연산과 축약을 거친 후 단일화된 결과만 외부로 출력하는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **축약 비율(Reduction Ratio)**: 연산에 투입된 전체 거대 입력 원본 데이터 양 대비 최종 출력되는 데이터 수량의 절감 비율이다.
- **데이터 재사용(Data Reuse)**: 1번 로드한 데이터를 상위 캐시에 올려두고 반복적인 계산에 재참조하는 메모리 접근 특성이다.
- **범용 연산(General-Purpose Computation)**: 조건 분기가 복잡하고 메모리 접근 구조가 일관되지 않은 일반적인 프로그램 로직이다.

</details>

| 비교 항목 | 메모리 내 연산 구조 (PIM) | 호스트 중심 처리 구조 (Host-Centric) |
|:---|:---|:---|
| 연산 수행 물리 위치 | 다이 내부의 각 메모리 뱅크 근접 연산기 | 중앙처리장치 및 그래픽스 코어 연산기 |
| 데이터 버스 전송 패턴 | 외부 이동을 배제하고 축약된 결과만 반환 | 대규모 원본 데이터를 메인 버스로 직접 전송 |
| 최적 타겟 워크로드 | 벡터 및 텐서 연산 등 높은 **축약 비율**을 가진 연산 | 분기가 복잡하고 **데이터 재사용**이 잦은 일반 연산 |
| 시스템 전력 소모 특성 | 외부 입출력 전력 감소 및 미세 연산 전력 추가 | 막대한 버스 입출력 및 호스트 고성능 연산 전력 소비 |
| 캐시 일관성 관리 | 호스트와 메모리 간 별도의 소프트웨어적 일관성 제어 필수 | 프로세서 하드웨어 수준에서 계층 간 일관성 자동 유지 |

#### 한줄 요약

- 메모리 내 연산은 대용량 데이터 축약과 버스 전력 절감에 탁월하고, 호스트 중심 처리는 복잡한 범용 연산과 캐시 재사용에 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 버퍼(Uncacheable Buffer)**: 일관성 붕괴를 방지하기 위해 캐시 적재를 강제로 우회시키는 운영체제 수준의 특수 메모리 설정 영역이다.
- **이관 지연(Offload Latency)**: 호스트가 명령을 발송하고 메모리 내 컨텍스트를 세팅하는 데 사전 소요되는 오버헤드 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 캐시 데이터와 갱신 데이터 간의 심각한 캐시 일관성 파괴 | 공유 구역에 **비캐시 버퍼** 할당 및 명시적 강제 동기화 지시어 적용 | 메모리 데이터 정합성 보장 및 구버전 데이터 참조 오류 방지 |
| 호스트가 명령을 발송하고 준비하는 **이관 지연** 발생으로 성능 상쇄 | 대규모 고축약 연산이 확실히 보장되는 워크로드만 선별적으로 이관 | 명령 발송 오버헤드 은닉 및 실질적인 시스템 가속 성능 확보 |
| 특정 메모리 주소가 하나의 뱅크로 쏠려 메모리 내 병렬 연산 무력화 | 뱅크 간 접근을 흩뿌리는 인터리빙 데이터 분산 배치 구조 적극 적용 | 뱅크 유휴 상태 완벽 소거 및 내부 대역폭 100% 한계 가동 |
| 일반 메모리 공정에 논리 연산 회로 혼재 탑재로 인한 발열 급증 및 단가 상승 | 단순한 미세 곱셈 누산기 위주 배치 및 동적 전압 주파수 발열 제어 | 칩 제조 단가 상승 최소 억제 및 발열 통제를 통한 성능 보장 |

#### 한줄 요약

- 비캐시 버퍼 설정으로 일관성을 유지하고 뱅크 인터리빙과 엄격한 워크로드 선별을 통해 내부 병렬 가속 효율을 극대화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **PIM 적용 판단 기준(PIM Adoption Criteria)**: 대상 알고리즘의 데이터 축약 비율, 뱅크 병렬성 확보 용이성, 데이터 재사용률을 종합 평가하여 오프로드 여부를 결정하는 가이드라인이다.

</details>

- 축약률과 뱅크 병렬성이 높으면 **메모리 내 연산**, 분기와 재사용이 잦으면 **호스트 연산**을 유지함

#### 한줄 요약

- 잠재적인 데이터 이동 전력 절감량과 이관에 따른 일관성 제어 비용을 정밀 비교하여 적용 범위를 신중하게 결정해야 한다.
