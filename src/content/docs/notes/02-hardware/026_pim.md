## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 내 처리(Processing-in-Memory, PIM)**: 메모리 셀 또는 뱅크 가까이에 연산 기능을 배치해 프로세서↔메모리 간 데이터 이동을 줄이는 컴퓨팅 방식.
- **데이터 이동 병목(Data Movement Bottleneck)**: 프로세서와 메모리 사이 데이터 전송 지연·에너지가 연산 성능을 제한하는 현상; AI 추론·빅데이터 처리의 주원인.
- **연산 오프로딩(Computation Offloading)**: 호스트가 수행하던 연산을 메모리 근처 연산기에 위임해 버스 트래픽을 줄이는 방식.

</details>

- 정의/개념: DRAM 뱅크 또는 로직 계층에 연산기를 직접 집적하여 **데이터 이동 병목**을 해소하는 지능형 메모리 아키텍처
- 배경/필요성: AI 행렬 연산 시 호스트와 메모리 간 **데이터 전송 에너지 소모** 및 버스 병목 심화

#### 한줄 요약
- 데이터를 프로세서까지 계속 가져오는 대신 데이터가 있는 메모리 쪽에서 계산해 이동량을 줄이는 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 뱅크와 근접 PIM 연산기 사이에서 활용 가능한 데이터 전송 능력; 외부 버스 대비 월등히 높음.
- **축약 연산(Reduction)**: 대량 입력 데이터를 합산·집계해 적은 결과로 줄이는 연산; PIM에 유리한 패턴.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 곱셈 결과를 누산해 벡터·행렬 계산을 수행하는 연산; AI 추론의 지배 연산.

</details>

- **내부 대역폭** 활용으로 메모리 뱅크 데이터를 외부 전송 없이 처리해 버스 트래픽 감소
- **축약 연산**으로 대량 원본 대신 소량 부분 결과만 호스트로 반환
- **MAC** 병렬 처리로 AI 추론의 행렬·벡터 연산을 오프로딩

#### 한줄 요약
- PIM은 내부에서 많은 데이터를 처리하고 합계나 부분 결과만 호스트로 보내므로, 외부 버스가 옮길 데이터가 줄어든다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PIM 연산 유닛(PIM Compute Unit)**: 메모리 뱅크 데이터에 산술·논리 연산을 수행하는 근접 연산기.
- **부분 결과(Partial Sum)**: 각 PIM 뱅크가 독립 계산한 중간 결과; 최종 결합 전 단계.
- **축약 버퍼(Reduction Buffer)**: 여러 PIM 뱅크의 **부분 결과**를 모아 최종 결과로 결합하는 저장·연산 영역.

</details>

```text
[PIM 시스템]
├─ 호스트 CPU·GPU  (연산 지시·결과 소비)
├─ 오프로딩 인터페이스  (연산 종류·주소 범위 전달)
├─ 메모리 뱅크 × N
│  └─ PIM 연산 유닛  (뱅크 데이터 직접 처리)
└─ 축약 버퍼  (부분 결과 결합·최종 반환)
```

선의 의미: 가지(`├─`)는 소유 관계; PIM 연산 유닛은 외부 버스를 거치지 않고 뱅크 내부 대역폭으로 데이터 접근

| 구성요소 | 책임 |
|:---|:---|
| 호스트 CPU·GPU | PIM 연산 요청 발행·최종 결과 소비 |
| 오프로딩 인터페이스 | 연산 종류·대상 주소 범위 전달 |
| 메모리 뱅크 | 원본 데이터 저장·**내부 대역폭** 제공 |
| **PIM 연산 유닛** | 뱅크 근처 데이터의 **MAC**·**축약** 병렬 처리 |
| **축약 버퍼** | 뱅크별 **부분 결과** 결합·최종 결과 보관 |

#### 한줄 요약
- 호스트는 계산을 지시하고, 뱅크 옆 연산기가 데이터를 직접 읽어 계산한 뒤 축약 결과만 돌려준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **뱅크 인터리빙(Bank Interleaving)**: 주소를 여러 메모리 뱅크에 분산해 내부 병렬 접근을 높이는 방식.
- **호스트 버스(Host Bus)**: 호스트 프로세서와 메모리 시스템 사이에서 명령·결과를 전달하는 연결 경로.

</details>

```text
호스트: PIM 연산 요청 (연산 종류·주소 범위)
      │
      ▼
1. 뱅크 인터리빙 및 데이터 분산: 여러 뱅크에 분산 배치
      │
      ▼
2. 뱅크별 PIM 로컬 병렬 처리: 내부 대역폭으로 직접 연산
      │
      ▼
3. 축약 버퍼 결합 및 반환: 부분 결과 결합 후 호스트 버스 전송
```

**동작 원리**

1. **뱅크 인터리빙 및 데이터 분산**: 호스트 요청 후 데이터를 여러 뱅크에 분산 배치
2. **뱅크별 PIM 로컬 병렬 처리**: 내부 대역폭으로 로컬 데이터 직접 계산
3. **축약 버퍼 결합 및 반환**: 부분 결과 결합 후 소량 결과만 호스트 반환

#### 한줄 요약
- PIM은 호스트가 대량 원본을 읽어 가는 대신 메모리 내부에서 나눠 계산하고 작은 결과만 돌려준다.

## Ⅴ. 종류 및 비교

| 처리 방식 | PIM | 호스트 중심 처리 |
|:---|:---|:---|
| 적용 기준 | 규칙적 대량 데이터·높은 **축약 비율** | 복합 제어·다양한 범용 연산 |
| 핵심 특징 | **내부 대역폭** 활용·버스 트래픽 감소 | CPU·GPU 실행 유닛의 유연한 연산 |
| 한계 | 지원 연산 제한·**일관성** 유지 비용·내부 발열 | 데이터 이동 지연·전력 증가 |

#### 한줄 요약
- 데이터가 크고 계산이 규칙적이면 PIM, 제어 흐름이 복잡하거나 연산 종류가 다양하면 호스트 처리가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 매핑(Uncacheable Mapping)**: 특정 공유 메모리 영역을 호스트 캐시에 보관하지 않도록 지정하는 속성; PIM과 캐시 불일치 방지.
- **뱅크 충돌(Bank Conflict)**: 여러 요청이 같은 메모리 뱅크에 집중되어 내부 병렬 처리가 제한되는 현상.
- **일관성 유지(Coherence Maintenance)**: 호스트 캐시와 PIM이 공유 데이터를 동일한 최신 상태로 관찰하게 하는 관리.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 캐시와 PIM 데이터 불일치 | **비캐시 매핑** 또는 캐시 정리·무효화 | 최신 데이터 관찰 일치 |
| 연산 요청이 한 뱅크에 집중해 **뱅크 충돌** | **뱅크 인터리빙**·데이터 재배치 | 내부 병렬성 향상 |
| 오프로딩 준비 비용이 결과 이득 상쇄 | **축약 비율** 높은 연산만 이관 | 명령·데이터 이동 비용 회수 |
| 메모리 내부 연산기 발열 증가 | 단순 연산 중심 배치·전력 제어 | 열 한도 내 처리량 유지 |

#### 한줄 요약
- PIM은 데이터 이동을 줄이는 대신 공유 데이터의 일관성·뱅크 배치·내부 열을 별도로 관리해야 한다.

## Ⅶ. 결론

- 축약 비율이 높은 반복 연산은 **PIM**, 복잡한 제어 흐름은 **호스트 처리** 선택

#### 한줄 요약
- PIM 선택은 메모리 안에서 계산 가능한가보다, 원본 이동을 줄인 이득이 오프로딩·일관성 관리 비용을 넘는지를 기준으로 판단한다.
