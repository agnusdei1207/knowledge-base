## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 내 처리(Processing-in-Memory, PIM)**: DRAM 메모리 셀 어레이 또는 뱅크(Bank) 내부에 연산 유닛(ALU/MAC)을 직접 집적하여 프로세서-메모리 간의 대규모 데이터 이동을 원천 제거하는 지능형 컴퓨팅 아키텍처.
- **데이터 이동 병목(Data Movement Bottleneck)**: 전통적 폰 노이만 구조에서 연산 유닛과 외부 메모리 간의 버스 대역폭 한계 및 전송 지연으로 인해 에너지의 60% 이상이 데이터 이동에 소모되는 현상.
- **연산 오프로딩(Computation Offloading)**: 호스트 프로세서(CPU/GPU)가 대규모 병렬 데이터 연산(행렬 곱셈, 벡터 합)을 메모리 내부 PIM 엔진으로 위임하여 시스템 버스 부하를 줄이는 기법.

</details>

- 정의/개념: DRAM 뱅크 또는 로직 계층에 연산 엔진을 내장하여 메모리 내부 초광폭 대역폭으로 직접 연산을 수행하는 **PIM(Processing-in-Memory) 아키텍처**
- 배경/필요성: 폰 노이만 아키텍처의 호스트-메모리 데이터 전송에 따른 **메모리 벽(Memory Wall) 및 데이터 이동 전력 낭비 극복**

#### 한줄 요약
- PIM은 메모리 내부에서 직접 연산을 수행하여 프로세서-메모리 간 데이터 전송 병목과 전력 소모를 획기적으로 줄인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 칩 내부의 뱅크와 연산 유닛 간에 수천 개의 전용 라인을 통해 제공되는 테라바이트급 초고속 내부 데이터 버스.
- **축약 연산(Reduction)**: 대규모 입력 벡터나 행렬 데이터를 합산, 평균, 최댓값 등으로 집계하여 소량의 결과값으로 압축하는 연산.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 두 수의 곱을 누적값에 더하는 연산으로, AI 딥러닝 행렬 곱셈(GEMM)의 핵심 연산.

</details>

- 테라급 내부 대역폭 활용: 외부 핀 제약이 없는 **내부 대역폭(Internal Bandwidth)**을 활용하여 뱅크 수준에서 수 테라바이트급 병렬 데이터 공급 실현
- 호스트 버스 트래픽 극소화: 대규모 원본 데이터를 칩 내부에서 연산하고 **축약 연산(Reduction)**을 통해 최종 요약 결과만 호스트로 전송
- AI 가속 최적화: 딥러닝 추론의 핵심인 **곱셈 누산(MAC)** 연산기를 뱅크마다 병렬 배치하여 전력 대비 성능(TOPS/W) 극대화

#### 한줄 요약
- 메모리 내부 대역폭으로 대량의 데이터를 병렬 연산하고 축약된 결과만 호스트로 반환하여 시스템 효율을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PIM 연산 유닛(PIM Compute Core / FPU)**: DRAM 뱅크 내부에 위치하여 뱅크로부터 직접 인출한 16/32비트 부동소수점 데이터의 SIMD 연산을 수행하는 경량 연산기.
- **부분 결과(Partial Sum)**: 각 뱅크의 PIM 연산 유닛이 로컬 데이터에 대해 독립적으로 계산한 중간 집계값.
- **축약 버퍼(Reduction Buffer / Tree)**: 각 뱅크에서 출력된 부분 결과들을 합산하여 최종 결과를 도출하고 호스트로 전달하는 버퍼.

</details>

```text
[호스트 CPU / GPU 가속기] ── (명령어 및 제어 오프로딩)
           │
           ▼
[PIM 메모리 서브시스템 (HBM-PIM / Aquabolt-XL)]
 ├─ [PIM 제어 로직] ────────── PIM 명령어 디코딩 및 뱅크 동기화
 │
 ├─ [메모리 뱅크 어레이]
 │   ├─ 뱅크 0 ── [PIM SIMD 연산 유닛 (MAC/ALU)] ──► 부분 결과 0 ─┐
 │   ├─ 뱅크 1 ── [PIM SIMD 연산 유닛 (MAC/ALU)] ──► 부분 결과 1 ─┼─► [축약 버퍼 (Reduction Unit)]
 │   │   ···                                                      │          │
 │   └─ 뱅크 N ── [PIM SIMD 연산 유닛 (MAC/ALU)] ──► 부분 결과 N ─┘          ▼
 └───────────────────────────────────────────────────────────────────► [호스트 버스 (최종 결과 반환)]
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 포함 관계; PIM 연산 유닛은 각 뱅크 옆에 집적되어 내부 버스로 데이터를 직접 읽음

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **호스트 프로세서** | 시스템 주 제어기 | 워크로드 분석 및 PIM 전용 FP16/INT8 연산 오프로딩 지시 | 커스텀 PIM 드라이버/런타임 |
| **PIM 제어 로직** | PIM 칩/베이스 다이 | 호스트 명령을 해석하여 뱅크별 병렬 연산 제어 신호 분배 | 상태 머신 제어기 |
| **PIM 연산 유닛** | 각 DRAM 뱅크 인접 | 뱅크 내부 데이터를 직접 인출하여 **MAC/ALU** 병렬 연산 수행 | 16-bit FP/INT SIMD 구조 |
| **축약 버퍼** | PIM 칩 공용 블록 | 각 뱅크에서 생성된 **부분 결과(Partial Sum)** 최종 집계 | 리덕션 트리(Reduction Tree) |

#### 한줄 요약
- PIM 시스템은 뱅크별 독립 연산 유닛, PIM 제어 로직, 축약 버퍼가 DRAM 내부에서 결합된 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **뱅크 인터리빙(Bank Interleaving)**: 연속된 주소를 복수 뱅크에 교차 배치하여 다수 뱅크를 동시 병렬 연산할 수 있도록 하는 기법.

</details>

```text
1. 호스트 프로세서의 PIM 가속 연산(GEMV, Softmax 등) 오프로딩 명령 발행
                      │
                      ▼
2. PIM 제어기가 대상 주소 범위를 16개 독립 DRAM 뱅크로 병렬 분배
                      │
                      ▼
3. 뱅크별 PIM 연산 유닛이 내부 초광폭 버스로 데이터를 읽어 병렬 MAC 연산 수행
                      │
                      ▼
4. 각 뱅크에서 생성된 부분 결과(Partial Sum)를 축약 버퍼로 전송
                      │
                      ▼
5. 축약 버퍼에서 최종 결과 취합(Reduction) ➔ 호스트 버스를 통해 최소 데이터만 반환
```

분기 결과: **데이터가 다수 뱅크에 균등 분산되면** 모든 뱅크 연산기가 100% 병렬 동작하나, **단일 뱅크 편중 시** 내부 연산 병렬성이 저하됨

#### 한줄 요약
- 호스트의 명령을 받은 PIM 제어기가 뱅크별 연산기를 병렬 가동하고, 축약 버퍼가 취합한 최종 결과만 호스트에 반환한다.

## Ⅴ. 종류 및 비교

| 비교 항목 | 메모리 내 처리 (PIM) | 전통적 호스트 중심 처리 (Host-Centric) |
|:---|:---|:---|
| 연산 위치 | **DRAM 뱅크 내부 / 실리콘 다이 직접 집적** | **호스트 CPU / GPU 내부 연산 코어** |
| 데이터 이동량 | **극소화 (최종 축약 결과만 시스템 버스로 전송)** | 매우 큼 (연산 대상 전체 원본 데이터를 버스로 전송) |
| 유효 대역폭 | **테라바이트급 칩 내부 대역폭 활용 ($> 1\text{ TB/s}$)** | 외부 시스템 버스/인터페이스 대역폭에 제약됨 |
| 연산 유연성 | 단순 연산(MAC, Addition, Activation) 위주 | **모든 복합 제어 및 범용 스칼라/벡터 연산 지원** |
| 에너지 효율 | **매우 높음 (데이터 전송 에너지 70% 이상 절감)** | 보통 (외부 버스 구동으로 인한 전력 소모 큼) |

#### 한줄 요약
- 규칙적이고 데이터 집약적인 AI 연산에는 PIM이 최적이며, 복잡한 제어 흐름과 범용 연산에는 호스트 프로세서가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 매핑(Uncacheable Mapping)**: PIM이 수정할 메모리 영역을 호스트 CPU 캐시에서 제외하여 데이터 불일치를 방지하는 기법.
- **뱅크 충돌(Bank Conflict)**: 복수의 연산 요청이 동일 뱅크에 집중되어 병렬성이 저하되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 CPU 캐시와 PIM 내부 연산 결과 간의 데이터 불일치 | **PIM 대상 영역을 비캐시(Uncacheable) 매핑 또는 플러시** | 캐시-메모리 간 데이터 일관성 보장 |
| 특정 뱅크로 연산이 쏠려 **뱅크 충돌(Bank Conflict)** 발생 | **뱅크 인터리빙 주소 매핑 및 텐서 타일링 분산** | 16개 뱅크 연산기 가동률 95% 이상 달성 |
| DRAM 공정 내 로직 집적으로 인한 발열 및 누설 전류 증가 | **저전력 경량 SIMD 연산기 설계 및 클록 게이팅** | DRAM 열 한도($<85^\circ\text{C}$) 내 안정 동작 보장 |

#### 한줄 요약
- 실무에서는 비캐시 매핑으로 일관성을 유지하고, 뱅크 인터리빙으로 연산 쏠림을 방지하며, 경량 설계를 통해 발열을 억제한다.

## Ⅶ. 결론

- 대규모 AI 언어 모델 및 추천 시스템의 메모리 벽을 극복하기 위해 **HBM 및 CXL 기반의 PIM(Processing-in-Memory) 아키텍처를 선별 도입**하고, 호스트와의 협력 처리를 위해 **PIM 전용 컴파일러 및 런타임 오프로딩 소프트웨어 스택**을 구축하며, 데이터 일관성은 **비캐시 영역 할당 및 동기화 장벽**으로 통제하는 차세대 지능형 메모리 시스템 아키텍처 확립

#### 한줄 요약
- PIM은 메모리 내 직접 연산으로 데이터 이동 병목을 제거하는 차세대 기술이며, 소프트웨어 스택과의 결합이 상용화의 핵심이다.
