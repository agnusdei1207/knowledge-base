## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모리 내 처리(Processing-in-Memory, PIM)**: DRAM 메모리 셀 어레이 또는 뱅크(Bank) 내부에 연산 유닛(ALU/MAC)을 직접 집적하여 프로세서-메모리 간의 대규모 데이터 이동을 원천 제거하는 지능형 컴퓨팅 아키텍처.
- **데이터 이동 병목(Data Movement Bottleneck)**: 전통적 폰 노이만 구조에서 연산 유닛과 외부 메모리 간의 버스 대역폭 한계 및 전송 지연으로 인해 에너지의 60% 이상이 데이터 이동에 소모되는 현상.
- **연산 오프로딩(Computation Offloading)**: 호스트 프로세서(CPU/GPU)가 대규모 병렬 데이터 연산(행렬 곱셈, 벡터 합)을 메모리 내부 PIM 엔진으로 위임하여 시스템 버스 부하를 줄이는 기법.

</details>

- 정의/개념: 메모리 셀 어레이 또는 뱅크(Bank) 내부에 연산 유닛(ALU/MAC)을 직접 통합하여 프로세서-메모리 간 대규모 데이터 이동을 최소화하는 **프로세서-메모리 융합 아키텍처**
- 배경/필요성: 폰 노이만 구조에서 CPU/GPU와 외부 DRAM 간의 대역폭 한계 및 데이터 이동 전력 소모(전체 시스템 에너지의 60% 이상)로 발생하는 **메모리 벽**을 극복하기 위해 도입

#### 한줄 요약
- PIM은 메모리 내부에서 직접 연산을 수행하여 프로세서-메모리 간 데이터 전송 병목과 전력 소모를 획기적으로 줄인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **내부 대역폭(Internal Bandwidth)**: 메모리 칩 내부의 뱅크와 연산 유닛 간에 수천 개의 전용 라인을 통해 제공되는 테라바이트급 초고속 내부 데이터 버스.
- **축약 연산(Reduction)**: 대규모 입력 벡터나 행렬 데이터를 합산, 평균, 최댓값 등으로 집계하여 소량의 결과값으로 압축하는 연산.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 두 수의 곱을 누적값에 더하는 연산으로, AI 딥러닝 행렬 곱셈(GEMM)의 핵심 연산.

</details>

- 외부 핀 제약 없는 **수 테라바이트급 내부 대역폭**을 활용하여 복수 DRAM 뱅크의 병렬 연산 동시 수행
- 뱅크 내에서 수행된 곱셈 누산(MAC) 데이터를 **칩 내부 축약 연산**으로 처리하여 최종 결과값만 호스트로 전송
- 호스트 연산 오프로딩을 통해 버스 전송 트래픽과 인터페이스 **데이터 이동 에너지 대폭 절감**

#### 한줄 요약
- 메모리 내부 대역폭으로 대량의 데이터를 병렬 연산하고 축약된 결과만 호스트로 반환하여 시스템 효율을 극대화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PIM 연산 유닛(PIM Compute Core / FPU)**: DRAM 뱅크 내부에 위치하여 뱅크로부터 직접 인출한 16/32비트 부동소수점 데이터의 SIMD 연산을 수행하는 경량 연산기.
- **부분 결과(Partial Sum)**: 각 뱅크의 PIM 연산 유닛이 로컬 데이터에 대해 독립적으로 계산한 중간 집계값.
- **축약 버퍼(Reduction Buffer / Tree)**: 각 뱅크에서 출력된 부분 결과들을 합산하여 최종 결과를 도출하고 호스트로 전달하는 버퍼.

</details>

```text
+-------------------------------------------------------------+
|                호스트 프로세서 (CPU / GPU / NPU)             |
+-------------------------------------------------------------+
                               | 오프로딩 명령 & 최종 요약 결과
                               v
+-------------------------------------------------------------+
|                   PIM 인터페이스 & 제어 로직                |
|  - PIM 제어 레지스터  - 명령어 디코더  - 뱅크 인터리버      |
+-------------------------------------------------------------+
         |                     |                     |
         v                     v                     v
+-----------------+   +-----------------+   +-----------------+
|   DRAM 뱅크 0   |   |   DRAM 뱅크 1   |   |   DRAM 뱅크 N   |
| +-------------+ |   | +-------------+ |   | +-------------+ |
| | 셀 어레이   | |   | | 셀 어레이   | |   | | 셀 어레이   | |
| +-------------+ |   | +-------------+ |   | +-------------+ |
|        | 내부 광폭  |        | 내부 광폭  |        | 내부 광폭
|        v   대역폭   |        v   대역폭   |        v   대역폭
| +-------------+ |   | +-------------+ |   | +-------------+ |
| | PIM FPU/ALU | |   | | PIM FPU/ALU | |   | | PIM FPU/ALU | |
| +-------------+ |   | +-------------+ |   | +-------------+ |
+-----------------+   +-----------------+   +-----------------+
         | 부분 합             | 부분 합             | 부분 합
         +---------------------+---------------------+
                               v
+-------------------------------------------------------------+
|               축약 연산 버퍼 (Reduction Unit)               |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표는 호스트 명령 하달, DRAM 뱅크와 PIM 연산 유닛 간 초광폭 내부 버스 전송, 부분 합 축약 결과를 호스트로 반환하는 데이터 경로를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| **호스트 인터페이스** | 호스트 프로세서의 **연산 오프로딩 명령**을 수신하여 내부 제어 신호로 변환 |
| **PIM 제어 로직** | 명령어 디코딩, 다중 **뱅크 스케줄링** 및 연산 타이밍 동기화 제어 |
| **DRAM 셀 어레이** | 대규모 텐서/벡터 원본 데이터를 저장하고 내부 비트라인으로 고속 공급 |
| **PIM 연산 유닛** | 뱅크 데이터에 대해 **곱셈 누산(MAC)** 및 벡터 부동소수점 병렬 연산 수행 |
| **축약 버퍼** | 각 뱅크 연산기가 산출한 **부분 결과**를 병합 집계하여 최종 결과 도출 |

#### 한줄 요약
- PIM 시스템은 뱅크별 독립 연산 유닛, PIM 제어 로직, 축약 버퍼가 DRAM 내부에서 결합된 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **뱅크 인터리빙(Bank Interleaving)**: 연속된 주소를 복수 뱅크에 교차 배치하여 다수 뱅크를 동시 병렬 연산할 수 있도록 하는 기법.

</details>

```text
+-------------------------------------------------------------+
|          호스트 프로세서의 PIM 가속 연산 오프로딩 명령 발행 |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       1. PIM 제어기의 뱅크 인터리빙 주소 분배 및 스케줄링   |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       2. DRAM 뱅크 내부 초광폭 대역폭을 통한 피연산자 인출  |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       3. 뱅크별 독립 PIM 연산 유닛(FPU/MAC) 동시 병렬 연산  |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       4. 각 뱅크 부분 결과(Partial Sum)의 축약 버퍼 전송    |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       5. 축약 트리 집계 완료 및 호스트 버스로 최종 결과 반환|
+-------------------------------------------------------------+
```

분기 결과: 데이터가 복수 뱅크에 **균등 분산(인터리빙)**되면 뱅크 가동률이 극대화되어 선형적 가속을 달성하나, **특정 뱅크에 편중(뱅크 충돌)**되면 대기 지연이 발생함

**동작 원리**

1. **호스트 가속 연산 오프로딩**: 호스트 CPU/GPU가 대규모 벡터 연산 커널을 감지하여 PIM 전용 명령어 패킷을 메모리 서브시스템으로 디스패치함
2. **뱅크 인터리빙 분배**: PIM 내부 컨트롤러가 입력 주소 공간을 분석하여 여러 DRAM 뱅크에 연산 작업과 피연산자 배치를 균등 분배함
3. **내부 초광폭 피연산자 공급**: DRAM 행 버퍼에서 활성화된 수천 비트의 원본 데이터를 외부 버스를 거치지 않고 로컬 PIM ALU로 직접 로드함
4. **뱅크별 독립 SIMD 병렬 연산**: 각 뱅크에 배치된 부동소수점 연산기가 내부 클록에 맞추어 곱셈 누산(MAC) 및 벡터 합을 병렬로 동시 수행함
5. **부분 결과 집계 및 최소 데이터 반환**: 뱅크별 부분 결과를 내부 축약 트리에서 최종 합산한 후, 압축된 단일 결과 벡터만 호스트 버스로 즉각 반환함

#### 한줄 요약
- 호스트의 명령을 받은 PIM 제어기가 뱅크별 연산기를 병렬 가동하고, 축약 버퍼가 취합한 최종 결과만 호스트에 반환한다.

## Ⅴ. 종류 및 비교

| 컴퓨팅 패러다임 | PIM (Processing-in-Memory) | 호스트 중심 처리 (Host-Centric) |
|:---|:---|:---|
| 적용 기준 | 규칙적 대규모 벡터·행렬 곱셈 등 데이터 집약 워크로드일 때 | 복잡한 제어 분기 및 비정형 알고리즘 중심 범용 연산일 때 |
| 핵심 특징 | **메모리 내부 연산 유닛** 탑재로 원본 데이터 전송 제거 | **CPU·GPU 고성능 코어**에서 메모리 데이터를 가져와 처리 |
| 한계 | 지원 연산 종류 제한 및 DRAM 공정 내 연산기 집적 난이도 | 프로세서-메모리 간 버스 병목 및 **데이터 이동 전력 급증** |

#### 한줄 요약
- 규칙적이고 데이터 집약적인 AI 연산에는 PIM이 최적이며, 복잡한 제어 흐름과 범용 연산에는 호스트 프로세서가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비캐시 매핑(Uncacheable Mapping)**: PIM이 수정할 메모리 영역을 호스트 CPU 캐시에서 제외하여 데이터 불일치를 방지하는 기법.
- **뱅크 충돌(Bank Conflict)**: 복수의 연산 요청이 동일 뱅크에 집중되어 병렬성이 저하되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 CPU 캐시와 메모리 내부 연산 결과 간 불일치 | PIM 작업 영역 **비캐시 매핑** 및 플러시 적용 | 캐시-메모리 간 데이터 일관성 유지 |
| 특정 메모리 뱅크로 연산이 집중되는 뱅크 충돌 현상 | **뱅크 인터리빙** 주소 할당 및 텐서 타일링 최적화 | 다중 뱅크 연산 유닛 가동률 90% 이상 유지 |
| DRAM 셀 영역 내 연산 로직 집적으로 인한 발열 상승 | 저전력 **경량 SIMD 설계** 및 클록 게이팅 적용 | DRAM 리프레시 한계 온도($<85^\circ\text{C}$) 내 안정 동작 보장 |

#### 한줄 요약
- 실무에서는 비캐시 매핑으로 일관성을 유지하고, 뱅크 인터리빙으로 연산 쏠림을 방지하며, 경량 설계를 통해 발열을 억제한다.

- 

#### 한줄 요약
- PIM은 메모리 내 직접 연산으로 데이터 이동 병목을 제거하는 차세대 기술이며, 소프트웨어 스택과의 결합이 상용화의 핵심이다.
