## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **오토사(Automotive Open System Architecture, AUTOSAR)**: 자동차 회사와 부품사들이 "제발 통일 좀 하자!"며 모여서 만든, 하드웨어 부품이 바뀌어도 소프트웨어를 뜯어고칠 필요 없게 만든 만국 공통 표준 아키텍처이다.
- **이씨유(Electronic Control Unit, ECU)**: 엔진 점화, 브레이크, 창문 모터 등 자동차 구석구석에 박혀서 각 기능을 멱살 잡고 통제하는 작은 컴퓨터(칩셋) 단말이다.
- **소프트웨어 재사용(Software Reuse)**: 현대차에서 쓰던 에어백 소프트웨어를 벤츠에 그대로 복사·붙여넣기 해도 칩셋 신경 안 쓰고 똑같이 돌아가게 만드는 극강의 재활용성이다.

</details>

- 정의: 차량용 전장 소프트웨어 계층(Application-RTE-BSW/ARA) 구조 및 인터페이스 메커니즘을 뼛속까지 규격화한 **오토사** 플랫폼
- 배경: 부품사(벤더)마다 소프트웨어를 지들 맘대로 짜서, 하드웨어 칩이 바뀔 때마다 코드를 통째로 갈아엎어야 하는 끔찍한 강한 결합(Tight Coupling)을 박살 내고 **소프트웨어 재사용**성을 극대화하기 위함

#### 한줄 요약

- 자동차 칩셋이 바뀌면 소프트웨어까지 다 새로 짜야 했던 노가다를 끝내기 위해, 하드웨어와 소프트웨어 사이를 찢어놓고 표준을 만든 글로벌 규격이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **표준 인터페이스(Standardized Interface)**: 위쪽 소프트웨어와 아래쪽 하드웨어가 직접 말 못 하게 막고, "앞으로 이 양식에 맞춰서만 서류(데이터) 넘겨라"고 못 박은 규칙이다.
- **에이알엑스엠엘(ARXML)**: 회사마다 쓰는 개발 프로그램이 달라도 서로 설계도를 주고받을 수 있게 만든, 오토사 전용 마크업(XML) 언어 기반의 공용 설계도이다.
- **클래식 플랫폼(Classic Platform)**: 0.01초 만에 브레이크를 밟아야 하는 무식하고 깐깐한 실시간 제어(하드 리얼타임)를 위해 뼛속까지 가볍게 만든 옛날 방식 플랫폼이다.
- **어댑티브 플랫폼(Adaptive Platform)**: 자율주행 카메라 영상처럼 무겁고 복잡한 데이터를 처리하기 위해 리눅스를 얹어서 화려하게 만든 최신형 고성능 플랫폼이다.

</details>

- 하드웨어 칩이 엎어져도 위쪽 애플리케이션 코드는 1도 안 고치게 막아주는 튼튼한 방파제인 **표준 인터페이스**를 도입함.
- 부품사들이 개발 툴이 달라도 서로 설계도를 주고받을 수 있게 하는 텍스트 기반 만국 공통어인 **에이알엑스엠엘**(ARXML)을 지원함.
- 단순 무식하고 빠른 **클래식 플랫폼**과 무겁지만 화려한 고성능 연산용 **어댑티브 플랫폼**으로 투트랙 분리 구조를 가짐.

#### 한줄 요약

- 코드를 칩에서 독립시키기 위해 표준 인터페이스와 공용 설계도(ARXML)를 쓰며, 급한 놈(클래식)과 무거운 놈(어댑티브)으로 플랫폼을 나눈다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **소프트웨어 컴포넌트(Software Component, SWC)**: 브레이크 밟기, 와이퍼 돌리기 등 핵심 기능 로직만 들어있고 하드웨어가 뭔지는 1도 모르는 순수한 앱 덩어리이다.
- **런타임 환경(Runtime Environment, RTE)**: 위층(응용 앱)과 아래층(하드웨어 통제) 사이에 낀 우체국 미들웨어로, 이놈이 편지를 분류해서 정확한 곳에 쏴주는 역할을 한다.
- **기본 소프트웨어(Basic Software, BSW)**: 운영체제(OS), 메모리 관리, 캔(CAN) 통신 등 앱이 돌아가기 위해 바닥에 깔아줘야 하는 인프라 코드들의 집합체이다.
- **마이크로컨트롤러 추상화 계층(MCAL)**: BSW의 가장 밑바닥에서 물리적인 칩셋 핀(Pin)과 회로를 직접 쑤시고 조종하는 노가다 하드웨어 통제 계층이다.
- **아라(AUTOSAR Runtime for Adaptive Applications, ARA)**: 묵직한 어댑티브 플랫폼 위에서 앱들이 통신하고 서비스를 찾아 쓸 수 있게 뚫어놓은 고성능 API 통신망이다.

</details>

```text
[ 오토사 하드웨어 분리 미들웨어 및 투트랙(Classic/Adaptive) 스택 아키텍처 ]

┌──────── 0.01초 하드 실시간 (클래식) ────────┐  ┌───── 기가급 연산 및 자율주행 (어댑티브) ─────┐
│       [ 응용 앱 (소프트웨어 컴포넌트) ]     │  │          [ 어댑티브 응용 프로그램 ]         │
├─────────────────────────────────────────────┤  ├─────────────────────────────────────────────┤
│         [ 런타임 환경 (RTE 가상 우체국) ]   │  │   [ 아라(ARA) API 및 빵빵한 기능 클러스터 ] │
├─────────────────────────────────────────────┤  ├─────────────────────────────────────────────┤
│   [ 기본 소프트웨어 (BSW) 및 하드웨어(MCAL) ] │  │  [ 리눅스(POSIX) OS 및 고성능 하이퍼바이저 ]│
└─────────────────────────────────────────────┘  └─────────────────────────────────────────────┘
```

| 구성요소 | 책임 |
|:---|:---|
| 응용 **소프트웨어 컴포넌트** | 브레이크 밟기, 에어백 터뜨리기처럼 하드웨어 칩이 뭔지 신경 안 쓰고 순수 로직만 짜놓은 최상위 캡슐 |
| **런타임 환경** 미들웨어 | 윗동네(응용 앱)와 아랫동네(하드웨어)가 직접 삿대질 못 하게 중간에서 통신과 호출을 엮어주는 가상 버스 우체국 |
| **기본 소프트웨어** 및 MCAL | OS 타이머, CAN 통신, 진단 기능을 제공하며, 가장 밑바닥(**마이크로컨트롤러 추상화 계층**)에서 하드웨어 칩 핀을 직접 쑤심 |
| 어댑티브 응용 및 **아라** | 리눅스(POSIX) 기반으로 자율주행 영상 처리 같은 빡센 서비스를 돌리며, 앱들에게 **아라** API를 통해 동적 통신망을 깔아줌 |

#### 한줄 요약

- 클래식은 응용 앱(SWC)과 하드웨어(BSW/MCAL) 사이에 런타임 우체국(RTE)을 끼워 넣은 구조고, 어댑티브는 리눅스 위에 아라(ARA)를 깔아 고성능 앱을 돌린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **플랫폼 할당(Platform Allocation)**: "너는 엔진 제어니까 클래식으로 가고, 너는 레이더 영상 분석이니까 어댑티브로 가라"고 급에 맞춰 노드 방을 배정해 주는 작업이다.
- **러너블(Runnable)**: 클래식 플랫폼의 RTE 우체국이 "야, 지금 0.01초 됐으니까 이 코드 빨리 돌려!"라고 채찍질할 때 뺑뺑이 도는 실행 함수 단위이다.
- **서비스 탐색(Service Discovery)**: 어댑티브 플랫폼에서 통신할 때, IP 주소를 하드코딩 안 하고 "주변에 카메라 영상 쏴줄 서비스 없나요?" 하고 동적으로 찾아 엮는 기술이다.

</details>

```text
[ 오토사 설계도(ARXML) 기반 칩셋 매핑 및 플랫폼 실행 십자포화 흐름 ]
                               │
                               ▼
   [ 1. 뼈대 설계: 어떤 데이터를 주고받을지 ARXML로 뼛속까지 시스템 명세서 작성 ]
                               │
                               ▼
     [ 2. 급 나누기: 0.01초가 급한 놈(클래식) vs 무거운 연산(어댑티브) 플랫폼 할당 ]
               /                                               \
    (하드 실시간 제어)                                       (리눅스 고성능 제어)
           │                                                 │
           ▼                                                 ▼
[ 3. 타이머에 맞춰 러너블 뺑뺑이 (클래식) ]        [ 3. 서비스 탐색으로 동적 엮기 (어댑티브) ]
           │                                                 │
           ▼                                                 ▼
[ 4. BSW/MCAL 통해 칩셋 핀에 직접 신호 꽂음 ]      [ 4. ARA 클러스터 통해 기가비트 이더넷 쏨 ]
           \                                                 /
            +-----------------------------------------------+
                               │
                               ▼
   [ 5. 종단 마감 검증: 데이터가 깨지지 않았는지, 브레이크가 제때 박혔는지 무자비하게 심판 ]
```

### 동작 원리

1. 뼈대 설계 계약(ARXML 구성): 이 부품은 어떤 데이터를 주고받을지 **에이알엑스엠엘**(ARXML)로 뼛속까지 시스템 명세서를 짬.
2. 급 나누기(플랫폼 할당): 0.01초가 급한 놈(에어백)은 클래식으로, 무거운 연산(카메라)은 어댑티브로 **플랫폼 할당**을 강제함.
3. 응용 로직 구동: 클래식은 타이머에 맞춰 **러너블**을 뺑뺑이 돌리고, 어댑티브는 필요한 서비스가 어딨는지 **서비스 탐색**으로 뒤짐.
4. 하부 인프라 통제: 칩셋 핀을 직접 건드리는 BSW/MCAL(클래식)이나 빵빵한 네트워크(ARA 기능 클러스터)를 통해 데이터를 쏨.
5. 종단 마감시간 검증: 보낸 데이터가 깨지지 않고(E2E 무결성), 0.1초 안에 브레이크가 제대로 꽂혔는지 데드라인 충족을 무자비하게 검증함.

#### 한줄 요약

- ARXML로 설계도를 짜고, 빠른 놈(클래식)과 무거운 놈(어댑티브)으로 나눈 뒤, 미들웨어(RTE/ARA)를 거쳐 하드웨어를 통제하고 마감 시간을 심판한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 구성(Static Configuration)**: 컴파일할 때 메모리와 통신 시간표를 돌덩이처럼 못 박아버려서, 차가 달리는 중에는 절대로 구조가 안 변하는 깐깐한 방식이다.
- **서비스 지향 아키텍처(Service-Oriented Architecture, SOA)**: 차가 달리면서도 새로운 서비스가 연결되면 알아서 IP를 찾고 동적으로 엮어버리는 유연한 리눅스(IT) 기반 통신 방식이다.

</details>

| 오토사 플랫폼 | **클래식 플랫폼** (Classic Platform) | **어댑티브 플랫폼** (Adaptive Platform) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 엔진, 섀시, 브레이크 제어처럼 단 0.001초라도 늦으면 사람이 다치는 살벌한 하드 실시간 제어 환경 | 내비게이션, 자율주행 카메라, 레이더처럼 칩셋 빵빵하고 기가바이트급 연산이 쏟아지는 고성능 서버 환경 |
| 아키텍처 핵심 구현 특징 | 컴파일할 때 모든 스케줄과 메모리를 돌덩이처럼 못 박아버리는 깐깐한 **정적 구성** 및 BSW/MCAL 스택 | 차가 달리면서도 필요한 서비스를 런타임에 동적으로 찾아서 엮는 유연한 **서비스 지향 아키텍처**(SOA) 및 ARA API |
| 극복해야 할 태생적 한계점 | 한 번 구워놓으면 OTA 무선 업데이트하기 빡세고, 무거운 카메라 영상이나 딥러닝 같은 컴퓨팅은 아예 돌리지도 못함 | 리눅스(POSIX) 기반이라 무겁고 부팅이 느려, 0.01초 안에 반응해야 하는 하드 실시간 생존 보장에는 치명적 제약 |

#### 한줄 요약

- 시간 약속이 생명인 엔진/브레이크는 정적인 클래식 플랫폼에 태우고, 복잡하고 무거운 자율주행 영상은 동적인 어댑티브 플랫폼에 태운다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **에이알엑스엠엘 스키마(ARXML Schema)**: 보쉬(Bosch)가 만든 설계도 파일을 콘티넨탈(Continental) 툴에서도 에러 없이 띄우기 위해, 문법과 구조를 강제로 통일시킨 헌법 같은 규칙이다.
- **원자적 갱신(Atomic Update)**: 무선 업데이트(OTA) 중에 99%에서 인터넷이 끊기면 차가 먹통이 되니까, "100% 성공 아니면 아예 예전 걸로 통째로 롤백!" 하는 모 아니면 도 갱신 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 보쉬(Bosch) 툴로 짠 ARXML 설계도를 타 벤더 툴에서 열었더니 에러 뿜고 다 깨지는 툴 체인 호환성 붕괴 사태 | 오토사 표준 위원회에서 시스템 전반의 **에이알엑스엠엘 스키마** 버전을 뼛속까지 통일하고 강제 동기화 | 벤더 간 밥그릇 싸움으로 인한 설계도(메타모델) 맵핑 붕괴 및 호환성 에러 100% 원천 차단 |
| 윗동네(응용)와 아랫동네(하드웨어)를 찢어놓느라, 중간 미들웨어(RTE)가 칩셋의 귀한 메모리를 잡아먹는 오버헤드 | 코드를 굽기 전에, 당장 안 쓰는 MCAL이나 BSW 모듈들을 가위로 난도질해 잘라내는 무자비한 가지치기 최적화 수행 | 제한된 칩셋 메모리가 터져나가는 끔찍한 오버헤드 압박을 해소하고 극강의 스택 경량화 달성 |
| 차가 달리면서 어댑티브 무선 업데이트(OTA) 하다가 중간에 끊겨서 차가 쇳덩이(벽돌)가 되는 끔찍한 위험 발발 | 업데이트가 100% 완벽히 안 끝나면 아예 예전 코드로 통째로 되돌려버리는 얄짤없는 **원자적 갱신** 및 롤백 적용 | 실패한 소프트웨어 갱신 때문에 시스템 전체가 먹통이 되는 A/S 복구 불능 사태를 완벽 방어 |

#### 한줄 요약

- 툴끼리 호환되게 ARXML 스키마를 빡세게 맞추고, 무거운 RTE 스택은 안 쓰는 코드를 잘라 다이어트시키며, OTA 업데이트 실패 시 무조건 원상 복구(롤백)시켜라.
