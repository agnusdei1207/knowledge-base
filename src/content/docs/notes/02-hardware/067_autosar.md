## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AUTOSAR(AUTomotive Open System ARchitecture)**: 글로벌 자동차 제조사(OEM)와 부품사(Tier-1)가 공동 개발한 개방형 자동차 전장 소프트웨어 표준 플랫폼.
- **RTE(Runtime Environment)**: 애플리케이션 소프트웨어 컴포넌트(SWC)와 하부 기본 소프트웨어(BSW) 간의 통신을 중계하는 미들웨어 계층.

</details>

- 정의/개념: 응용·**RTE(Runtime Environment)**·기본 소프트웨어·하드웨어 추상화의 계층 구조를 표준화한 개방형 전장 플랫폼 **AUTOSAR(AUTomotive Open System ARchitecture)**
- 배경/필요성: 제어기·공급사·차종마다 인터페이스와 기반 계층이 다르면 같은 기능을 매번 다시 통합하고 다시 검증해야 함

#### 한줄 요약
- 이 표준이 겨눈 것은 코드 품질이 아니라 조직 사이의 인터페이스이며, 그래서 기술 규격이면서 동시에 산업 협업 규약으로 작동한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VFB(Virtual Function Bus)**: 하드웨어 배치와 무관하게 소프트웨어 컴포넌트 간 통신을 가상화하여 설계하는 추상화 버스.
- **ARXML(AUTOSAR XML)**: 시스템 토폴로지, 통신 매트릭스, 소프트웨어 컴포넌트 인터페이스 설정을 기술하는 표준 교환 포맷.

</details>

- 계층 분리로 **SWC(Software Component)** 특정 칩에 묶이지 않도록 의존성 차단
- 실시간 제어용 플랫폼과 고성능 서비스 지향 플랫폼으로 이원화
- **ARXML(AUTOSAR XML)** 기술서를 입력으로 삼는 모델 주도 개발과 코드 자동 생성 지원

#### 한줄 요약
- 표준화의 실익은 코드 생성이 아니라 설계 산출물이 회사 경계를 넘어 그대로 전달된다는 데 있으며, 그 매개가 형식 기술서다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SWC(Software Component)**: 차량의 특정 제어 기능을 구현한 최상위 독립 소프트웨어 모듈.
- **BSW(Basic Software)**: OS, 메모리 관리, CAN/LIN 통신 스택, 진단(UDS) 등 공통 필수 서비스를 제공하는 계층.
- **MCAL(Microcontroller Abstraction Layer)**: 특정 반도체 칩의 레지스터를 직접 제어하는 최하위 하드웨어 드라이버 계층.

</details>

```text
[AUTOSAR 계층 구조]
├─ 응용 소프트웨어 컴포넌트 계층
│  └─ 기능별 SWC (엔진·제동·램프 제어)
├─ 런타임 환경 (SWC 간 통신과 하위 서비스 호출 중계)
├─ 기본 소프트웨어
│  ├─ 서비스 계층 (실시간 OS·통신 관리·진단)
│  ├─ ECU 추상화 계층 (외장 칩까지 포함한 통합 인터페이스)
│  └─ 마이크로컨트롤러 추상화 계층 (칩 레지스터 직접 제어)
└─ 마이크로컨트롤러 하드웨어
```

선의 의미: 가지(`├─`)는 소유 관계이며, 위 계층은 아래 계층을 건너뛰어 호출할 수 없고 반드시 런타임 환경을 통과

| 구성요소 | 책임 |
|:---|:---|
| 애플리케이션 SWC | 포트와 인터페이스로 규정된 차량 기능 로직 수행 |
| 런타임 환경 | **VFB(Virtual Function Bus)** 설계를 실제 배치에 맞춰 구현한 자동 생성 미들웨어 |
| 서비스 계층 | 실시간 OS·통신 관리·진단 등 공통 서비스 제공 |
| ECU 추상화 계층 | 외장 칩까지 포함한 통합 인터페이스 제공 |
| **MCAL(Microcontroller Abstraction Layer)** | 칩 내부 주변장치 레지스터를 직접 제어 |

#### 한줄 요약
- **BSW(Basic Software)** 아래 계층이 두꺼울수록 이식성은 오르고 실행 효율은 떨어지므로, 이 구조의 대가는 성능이 아니라 메모리로 먼저 나타난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Runnable**: 특정 이벤트(주기 타이머, 데이터 수신 등)에 의해 RTE에 의해 트리거되어 실행되는 SWC 내부의 최소 함수 단위.

</details>

```text
시스템 요구사항·통신 매트릭스 정의
        │
   ARXML로 SWC 연결과 신호 매핑 모델링
        │
   타깃 칩 클록·통신 속도·메모리 섹션 설정
        │
   생성기가 런타임 환경과 기본 소프트웨어 코드 자동 생성
        │
   생성 코드가 자원 예산 안에 들어오는가?
   ┌────┴─────┐
아니오          예
   │             │
미사용 모듈     알고리즘 코드와 링크해 통합 빌드
비활성화 후       │
재생성        OS 타이머 틱에 맞춰 Runnable 주기 호출
   │             │
   └────┬────────┘
        │
   (다시 자원 검토)
```

분기 결과: 손으로 작성하는 부분은 알고리즘뿐이고 나머지는 설정에서 생성되므로, 문제가 생기면 코드가 아니라 설정 파일을 고쳐야 하는 구조가 됨

#### 한줄 요약
- **Runnable** 호출 주기까지 설정에서 결정되므로 실시간 특성이 코드 리뷰로는 드러나지 않으며, 검증 대상이 소스에서 구성 파일로 옮겨 간다.

## Ⅴ. 종류 및 비교

| AUTOSAR 플랫폼 범주 | AUTOSAR Classic | AUTOSAR Adaptive | Non-AUTOSAR 레거시 | ROS 2 / AP-Linux |
|:---|:---|:---|:---|:---|
| 적용 기준 | 제동·조향·엔진 등 실시간 결정론적 ECU | 자율주행·인포테인먼트·도메인 제어기 | 초저가 단일 목적 단순 센서 노드 | 자율주행 로보틱스 연구 및 시제품 |
| 핵심 특징 | 정적 구성과 신호·서비스 기반 ECU 통신 | POSIX 기반 서비스 지향 애플리케이션 | 제품별 최소 전용 구성 | DDS 기반 노드·토픽 통신 |
| 한계 | 동적 서비스와 고성능 애플리케이션에 제약 | 복잡한 배포·서비스 관리와 큰 자원 요구 | 표준 인터페이스·도구 재사용 범위 제한 | 차량 양산 플랫폼 통합·안전 증거 별도 필요 |

#### 한줄 요약
- 네 플랫폼은 정적 확정과 동적 유연성 사이의 눈금이며, 동적으로 갈수록 기능은 늘지만 안전 증거를 만들기는 급격히 어려워진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **E2E(End-to-End) 보호**: 차량 네트워크 통신 중 데이터 변조, 유실, 순서 바뀜을 감지하기 위해 CRC와 카운터를 붙이는 기능 안전 프로토콜.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 도구·기술서 버전 불일치로 통합 단계 오류 | 메타모델 버전 고정과 기술서 유효성 자동 검증 | 설정 충돌을 생성 이전에 탐지 |
| 계층 오버헤드로 제어기 메모리 부족 | 미사용 모듈 비활성화와 복합 드라이버로 긴급 경로 직결 | 바이너리 크기 축소와 여유 확보 |
| 통신 데이터의 유실·순서 오류·위조 위험 | **E2E(End-to-End) 보호** 기반 전송 오류를, 별도 인증으로 위조를 검증 | 안전 오류와 보안 위협의 검출 경로 분리 |
| 원격 소프트웨어 업데이트 실패로 기능 손상 | 플랫폼별 업데이트 관리와 이중 파티션 롤백 적용 | 손상 이미지 활성화 차단과 이전 버전 복구 |

#### 한줄 요약
- 네 문제 중 셋이 코드가 아니라 설정·버전·배포에서 나오므로, 이 플랫폼에서 품질 관리의 대상은 프로그램이 아니라 구성 형상이다.

## Ⅶ. 결론

- 정적 제어와 자원이 작은 제어기는 실시간 플랫폼을, 동적 서비스와 고성능 컴퓨팅은 서비스 지향 플랫폼을 선택하고, 두 계열을 함께 쓸 때는 안전 경계와 통신 정책을 명시적으로 분리

#### 한줄 요약
- 표준을 도입한다고 재사용이 생기는 것이 아니라 인터페이스를 표준 형식으로 합의해야 생기며, 도구만 들여오고 합의를 건너뛴 조직에서 도입이 실패한다.
