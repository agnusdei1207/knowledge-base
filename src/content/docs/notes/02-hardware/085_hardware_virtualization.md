## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하드웨어 가상화(Hardware-Assisted Virtualization)**: CPU 칩 자체에 가상 머신 전용 명령어를 박아 넣어서, 가짜 OS가 소프트웨어 번역 없이 CPU를 다이렉트로 씹고 뜯게 해주는 마법이다.
- **하이퍼바이저(Hypervisor/VMM)**: 가짜 컴퓨터(VM)들에게 CPU랑 메모리를 던져주고, 헛짓거리 하면 멱살 잡고 통제하는 시스템의 절대 건물주이다.
- **가상 머신(Virtual Machine, VM)**: 건물주(하이퍼바이저)한테 자원을 빌려서 구동되는, 지가 진짜 컴퓨터인 줄 착각하는 세입자 운영체제이다.

</details>

- 정의: CPU 하드웨어 단에 가상화 전용 명령어(VT-x/AMD-V)와 매핑 구조(VMCS, EPT)를 쑤셔 박아서, 게스트 OS가 소프트웨어 변환 없이 다이렉트로 CPU를 씹고 뜯게 해주는 **하드웨어 가상화** 기술
- 배경: 가짜 윈도우(VM)가 내린 명령을 진짜 윈도우가 알아듣게 매번 통역(소프트웨어 변환)해 주다 보니 CPU가 피 토하고 시스템 전체가 뻗어버리는 극악의 오버헤드를 타파하기 위함

#### 한줄 요약

- CPU 칩 차원에서 가짜 OS를 다이렉트로 지원해 줘서, 번역하느라 느려 터지던 가상 머신의 속도를 획기적으로 올렸다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **브이티엑스 / 에이엠디브이(VT-x / AMD-V)**: 인텔과 AMD가 CPU 안에 박아놓은 가상화 전용 하드웨어 명령어 세트이다.
- **브이엠씨에스/브이엠씨비(VMCS/VMCB)**: 세입자(VM)가 뭐 했는지, 언제 멱살 잡고 건물주한테 끌고 올 건지 적어놓은 무시무시한 하드웨어 블랙박스 장부이다.
- **이피티/엔피티(EPT/NPT)**: 가짜 메모리 주소를 진짜 물리 주소로 두 번이나 번역하느라 헐떡이는 걸, 하드웨어가 직빵으로 번역해 주는 전용 통역기이다.

</details>

- 하이퍼바이저(Root)와 게스트(Non-Root)의 서열을 CPU 칩 내부에서 물리적으로 완전히 갈라버림.
- 가짜 윈도우가 진짜 CPU를 건드릴 때마다 **브이엠씨에스/브이엠씨비(VMCS/VMCB)** 장부에 상태를 적어놓고 하이퍼바이저가 멱살을 잡고 통제함.
- 가짜 메모리 주소를 진짜 물리 주소로 두 번이나 번역하느라 헐떡이는 섀도 페이지 테이블 대신, 하드웨어가 직빵으로 번역해 주는 **이피티/엔피티(EPT/NPT)**를 갈겨버림.

#### 한줄 요약

- 계급을 나누고(Root/Non-Root), 장부(VMCS)로 감시하며, 메모리 번역(EPT)을 하드웨어로 처리하는 게 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가상 입출력 가상화 기술(VT-d / AMD-Vi)**: 세입자가 랜카드나 그래픽카드에 직접 빨대 꽂게 해주고 남의 거 못 건드리게 막는 하드웨어 방화벽이다.
- **가상 시피유(Virtual CPU, vCPU)**: 건물주가 찐 CPU 코어 시간을 쪼개서 세입자한테 던져주는 가짜 CPU 쪼가리이다.
- **브이엠엑스 루트/비루트 모드(VMX Root / Non-Root Mode)**: 건물주가 노는 무소불위의 영역(루트)과 세입자가 갇혀서 노는 감옥(비루트) 모드이다.

</details>

```text
[ 하드웨어 지원 가상화 십자포화 계급 프레임워크 ]
                          [ EPT/NPT (하드웨어 주소 통역기) ]
                                          │
[ 게스트 VM (세입자) ] ── [ CPU 가상화 확장 (감시 카메라) ] ── [ 하이퍼바이저 (절대 건물주) ]
                                                                          │
                                                         [ VT-d 가상 방화벽 (장치 빨대) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 게스트 VM | "나 가짜인 줄 모르지?" 하며 지가 진짜 컴퓨터인 줄 알고 설치대며 CPU에 직접 명령을 갈기는 세입자 윈도우/리눅스 |
| CPU 가상화 확장 | 세입자가 선 넘으면(특권 명령) 바로 멱살 잡고 건물주(하이퍼바이저)한테 일러바치는 **브이엠엑스(VMX)** 감시 카메라 |
| 하이퍼바이저 제어부 | 세입자들한테 **가상 시피유(vCPU)** 쪼가리 던져주고, 헛짓거리 하면 트랩(Trap) 걸어서 참교육 시키는 절대 권력 건물주 |
| **이피티/엔피티(EPT/NPT)** | 세입자가 부르는 엉터리 가상 주소를 진짜 물리 메모리 주소(HPA)로 빛의 속도로 번역해 주는 하드웨어 직통 통역기 |
| **가상 입출력(VT-d/AMD-Vi)** | 세입자가 랜카드나 그래픽카드에 직접 빨대(Passthrough) 꽂게 해주고 남의 거 못 건드리게 멱살 잡는 하드웨어 방화벽 |

#### 한줄 요약

- 건물주(하이퍼바이저)가 VMX와 EPT라는 하드웨어 몽둥이를 들고 세입자(게스트)를 효율적으로 쥐어팬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **브이엠 엔트리(VM Entry)**: 건물주가 뒤로 빠지고 세입자한테 "CPU 써라" 하고 제어권을 넘겨주는 입장 절차이다.
- **브이엠 엑시트(VM Exit)**: 세입자가 시스템 끄기 같은 헛짓거리(특권명령)를 하면 멱살 잡혀서 건물주한테 강제 소환되는 퇴장 절차이다.

</details>

```text
[ 하드웨어 가상머신 제어권 십자포화 전환 흐름 ]
                                 │
                                 ▼
   [ 1. 장부 세팅: 건물주가 "사고 치면 알려라" 하고 VMCS 블랙박스 세팅 ]
                                 │
                                 ▼
         [ 2. 세입자 투입: 건물주 빠지고 세입자가 다이렉트로 CPU 씹고 뜯음 (VM Entry) ]
                                 │
                 ┌───────────────┴───────────────┐
            ( 메모리 쓸 때 )                ( 선 넘는 짓 할 때 )
                 ▼                               ▼
       [ 3. 하드웨어 주소 번역 ]         [ 4. 감시카메라 발동 (VM Exit) ]
           ( EPT가 알아서 번역 )                 │
                                                 ▼
                                     [ 5. 건물주 등판 및 참교육 ]
                                     ( 수습 후 다시 2번으로 뺑뺑이 )
```

### 동작 원리

1. 제어권 적재: 건물주가 **VMCS** 장부에 "세입자 들어감, 사고 치면 알려라" 하고 조건을 빡세게 세팅함.
2. 세입자 투입: 건물주가 뒤로 빠지고(**브이엠 엔트리**), 세입자가 CPU를 다이렉트로 물고 뜯고 씹으며 실행됨.
3. 하드웨어 주소 번역: 세입자가 메모리 달라고 징징대면 **EPT/NPT**가 하드웨어적으로 알아서 척척 번역해 줌.
4. 멱살 트랩: 세입자가 시스템 끄기 같은 선 넘는 짓(특권 명령)을 하면, 감시 카메라가 발동해 **브이엠 엑시트**를 때리고 건물주한테 강제 소환됨.
5. 건물주 참교육: 건물주가 사태를 수습하고 다시 세입자한테 제어권을 던져주며 뺑뺑이를 돌림.

#### 한줄 요약

- 평소엔 세입자가 다이렉트로 쓰다가(Entry), 선 넘는 짓 할 때만 멱살 잡혀 끌려 나온다(Exit).

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **바이너리 변환(Binary Translation)**: 하드웨어 가상화가 없던 시절, 세입자가 날린 명령어를 소프트웨어가 실시간으로 낚아채서 안전한 코드로 통역해 주던 똥꼬쇼이다.
- **준가상화(Para-Virtualization)**: 세입자 OS를 뜯어고쳐서, 자기가 가짜인 걸 깨닫게 하고 건물주한테 굽실거리게(Hypercall) 만든 개조형 가상화이다.

</details>

| 비교 항목 | **하드웨어 가상화** (VT-x / AMD-V) | **전가상화 바이너리 변환** (Binary Translation) | **준가상화** (Para-Virtualization) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | CPU 칩에 가상화 기능이 박혀 있어서 윈도우든 리눅스든 원본 그대로 씹고 뜯으며 무식하게 돌릴 시 | 옛날 구닥다리 CPU라서 하드웨어 지원이 아예 없을 때, 피 토하며 소프트웨어로 강제 변환할 시 | 세입자 커널 소스를 뜯어고쳐서 건물주랑 짝짜꿍(Hypercall) 맞춰 돌아가게 개조할 시 |
| 아키텍처 핵심 구현 특징 | CPU 자체가 가짜 윈도우랑 진짜 윈도우를 하드웨어적으로 알아서 구분하고 통제하는 상남자식 아키텍처 | 세입자가 선 넘는 명령 날리면 소프트웨어가 실시간으로 낚아채서 안전한 코드로 둔갑시키는 눈물겨운 똥꼬쇼 | 세입자가 지가 가짜인 걸 인지하고, 선 넘을 때 스스로 건물주한테 "이것 좀 해주세요" 하고 굽실거림 |
| 극복해야 할 태생적 한계점 | 건물주랑 세입자 사이에 들락날락(**VM Exit/Entry**)을 너무 자주 하면 스위칭 딜레이 때문에 CPU가 박살 남 | 코드를 일일이 까보고 통역(변환)하느라 서버 CPU 부하가 폭발하고 속도가 끔찍하게 느려 터짐 | 윈도우처럼 소스 코드가 비공개인 OS는 뜯어고칠 수가 없어서 사실상 리눅스 전용 반쪽짜리 기술 |

#### 한줄 요약

- OS 안 고치고 CPU 빨로 돌리면 하드웨어 가상화, 억지로 통역하면 바이너리 변환, OS 개조하면 준가상화이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **에스알 아이오브이(Single Root I/O Virtualization, SR-IOV)**: 랜카드 하나를 수십 개로 쪼개서 세입자들한테 직접 빨대 꽂게 해주는 하드웨어 가상화 장비이다.
- **버티오(Virtio)**: 가짜 장치 돌리느라 버벅대는 걸 막기 위해, 세입자랑 건물주가 하이패스처럼 통과하는 전용 드라이버 규격이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 세입자가 랜카드 한 번 쓸 때마다 건물주한테 끌려가는 **브이엠 엑시트**(VM Exit)가 미친 듯이 터져서 서버가 뻗음 | 건물주 안 거치고 랜카드에 다이렉트 빨대 꽂는 **에스알 아이오브이(SR-IOV)**랑 **버티오(Virtio)** 드라이버 떡칠 | 멱살 트랩(Exit)이 사라져서 10기가 랜카드 속도를 0.001초 지연 없이 극한까지 쥐어짬 |
| 가짜 주소를 진짜 주소로 두 번씩 번역(**EPT**)하느라 캐시(TLB)가 다 박살 나고 메모리 딜레이가 폭발하는 재앙 | 잘게 쪼개진 메모리 대신 집채만 한 메모리 덩어리(Huge Pages)로 냅다 할당해서 번역할 거리 자체를 없애버림 | 섀도 테이블 붕괴를 막고 주소 변환 오버헤드를 씹어먹어 메모리 접근 속도 극강 사수 |
| 가짜 CPU(vCPU)는 1번 소켓에서 도는데, 메모리는 2번 소켓에 박혀 있어서 남의 동네까지 데이터 퍼오느라 지연 폭발 | vCPU랑 물리 메모리를 멱살 잡고 같은 동네(NUMA 친화도)에 강제로 결박시켜서 원격 접근을 원천 차단 | 옆 동네 메모리 퍼오는 끔찍한 딜레이를 쳐내고 가상 머신 지연시간을 한계점까지 단축 |

#### 한줄 요약

- I/O는 SR-IOV로 직결하고, 메모리 번역 딜레이는 큼직한 할당(Huge Pages)으로 틀어막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가상화 선택 기준(Virtualization Technology Selection Criteria)**: OS를 뜯어고칠 수 있는지, 성능이 깡패처럼 필요한지 따져서 어떤 가상화 방식을 쓸지 결정하는 잣대이다.

</details>

- **가상화 선택 기준** 원칙에 따라, 안 고친 순정 OS는 **하드웨어 가상화**, I/O 속도 몰빵은 **준가상화(버티오)**, 옛날 기계는 **바이너리 변환** 채택 기조 확립함

#### 한줄 요약

- 요새 칩은 무조건 하드웨어 가상화를 쓰고, I/O 버벅대면 준가상화 드라이버를 섞어 써라.
