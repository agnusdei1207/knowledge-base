## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **하드웨어 가상화**: 처리기가 게스트 명령의 직접 실행과 자원 격리를 지원하는 기술이다.
- **하이퍼바이저**: 가상머신의 물리 자원과 실행 상태를 중재하는 제어 계층이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령 실행과 시스템 자원 제어를 담당하는 처리 장치이다.
- **가상 머신(Virtual Machine, VM)**: 격리된 가상 하드웨어에서 게스트 운영체제를 실행하는 시스템이다.

</details>

- 정의/개념: **하드웨어 가상화**는 **CPU**의 특권 수준과 2단계 주소 변환 및 VM 제어 구조를 이용하여 **가상 머신** 명령의 직접 실행과 자원 격리를 지원하는 기술이다.
- 배경/필요성: 모든 민감 명령과 주소를 소프트웨어로 해석•변환하면 실행 비용이 크고 운영체제 호환과 정확한 특권 제어가 복잡해진다.

#### 한줄 요약

- **하드웨어 가상화**는 게스트의 일반 명령을 직접 실행하고 통제가 필요한 사건에서만 **하이퍼바이저**로 전환한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **인텔 x86 가상화 기술(Intel Virtualization Technology for x86, VT-x)**: 게스트 실행 모드와 전환 기능을 제공하는 확장이다.
- **AMD 가상화(AMD Virtualization, AMD-V)**: AMD 처리기에 게스트 실행 모드와 전환 기능을 제공하는 확장이다.
- **가상 머신 제어 구조(Virtual Machine Control Structure, VMCS)**: 인텔 처리기의 게스트 상태와 전환 조건 저장 구조이다.
- **가상 머신 제어 블록(Virtual Machine Control Block, VMCB)**: AMD 처리기의 게스트 상태와 전환 조건 저장 구조이다.
- **확장 페이지 테이블(Extended Page Tables, EPT)**: 인텔 처리기의 2단계 주소 변환 표이다.
- **중첩 페이지 테이블(Nested Page Tables, NPT)**: AMD 처리기의 2단계 주소 변환 표이다.

</details>

- **VT-x**와 **AMD-V**는 비특권 명령을 직접 실행해 변환 비용을 줄인다.
- **VMCS**와 **VMCB**는 게스트 상태와 전환 조건을 저장해 통제 사건을 중재한다.
- **EPT**와 **NPT**는 2단계 주소 변환으로 게스트 메모리를 격리한다.

#### 한줄 요약

- VM 전환과 2단계 주소 변환 빈도가 높을수록 오버헤드가 증가한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **게스트 VM(Guest VM)**: 격리된 가상 하드웨어에서 운영체제와 응용을 실행하는 구성이다.
- **CPU 가상화 확장(CPU Virtualization Extension)**: 게스트 진입•탈출과 직접 실행 모드를 제공하는 구성이다.
- **하이퍼바이저 제어부(Hypervisor Control)**: VM 실행 상태와 물리 자원 접근을 중재하는 구성이다.
- **EPT•NPT**: 게스트 물리 주소를 호스트 물리 주소로 변환하는 2단계 페이지 테이블이다.
- **가상 입출력(Virtual I/O)**: 물리 장치를 VM별 논리 장치로 중재하는 구성이다.
- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: DMA 주소를 변환하고 장치별 접근 범위를 격리하는 하드웨어이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치가 CPU를 거치지 않고 메모리를 읽고 쓰는 전송 방식이다.

</details>

```text
                         [EPT•NPT]
                             |
                             |
[게스트 VM] -- [CPU 가상화 확장] -- [하이퍼바이저 제어부] -- [가상 I/O•IOMMU]
```

선의 의미: 게스트 실행과 하이퍼바이저 사이에 CPU 가상화 확장이 놓이고, 주소 변환과 장치 격리 자원이 결합된 정적 가상화 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 게스트 VM | 운영체제•응용 실행 |
| CPU 가상화 확장 | 진입•탈출 전환 |
| 하이퍼바이저 제어부 | 상태•자원 중재 |
| EPT•NPT | 2단계 주소 변환 |
| 가상 I/O•IOMMU | 장치•DMA 격리 |

#### 한줄 요약

- **게스트 VM**, **CPU 가상화 확장**, **하이퍼바이저 제어부**와 메모리•장치 격리 구성의 구조이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **VM Entry**: 하이퍼바이저가 게스트에 제어권을 넘기는 전환이다.
- **VM Exit**: 통제가 필요한 사건에서 처리기가 하이퍼바이저로 제어권을 회수하는 전환이다.
- **민감 명령**: 자원 통제나 시스템 상태에 영향을 주어 하이퍼바이저 중재가 필요한 명령이다.
- **VM 제어 상태 적재**: 게스트 상태와 VM Exit 조건 및 접근 권한을 설정하는 단계이다.
- **VM Entry·게스트 직접 실행**: 게스트 상태로 진입해 허용된 일반 명령을 직접 수행하는 단계이다.
- **EPT·NPT 주소 변환**: 게스트 물리 주소를 호스트 물리 주소로 다시 변환하는 단계이다.
- **VM Exit·상태 저장**: 통제 사건에서 게스트 상태와 종료 원인을 저장하고 제어권을 회수하는 단계이다.
- **하이퍼바이저 중재**: 종료 원인의 장치와 권한 정책을 처리하고 게스트를 재개하는 단계이다.

</details>

```text
1. VM 제어 상태 적재
          │
          ▼
2. VM Entry•게스트 직접 실행
          │
          ▼
┌──────────── 게스트 실행 반복 ───────────┐
│ 3. EPT•NPT 주소 변환                    │
│          │                               │
│          ▼                               │
│   [민감 명령•I/O•예외 발생]             │
│       ┌──┴─────────┐                     │
│       │ 없음       │ 발생                │
│       │            ▼                     │
│       │     4. VM Exit•상태 저장         │
│       │            │                     │
│       │            ▼                     │
│       │     5. 하이퍼바이저 중재         │
│       │            │                     │
│       └────────────┴── VM Entry로 복귀   │
└──────────────────────────────────────────┘
```

### 동작 원리

1. **VM 제어 상태 적재**: 하이퍼바이저가 게스트 레지스터 상태와 VM Exit 조건 및 접근 권한을 설정한다.
2. **VM Entry•게스트 직접 실행**: CPU가 게스트 상태로 진입하여 허용된 일반 명령을 하이퍼바이저 개입 없이 실행한다.
3. **EPT•NPT 주소 변환**: 게스트 페이지 테이블이 가상 주소를 게스트 물리 주소로 바꾸고 EPT•NPT가 이를 호스트 물리 주소로 다시 변환한다.
4. **VM Exit•상태 저장**: 특권 사건이나 정책 위반이 발생하면 CPU가 게스트 상태와 종료 원인을 저장하고 제어권을 회수한다.
5. **하이퍼바이저 중재**: 하이퍼바이저가 종료 원인에 따른 장치•권한 정책을 처리한 뒤 게스트를 다시 실행한다.

#### 한줄 요약

- **민감 명령** 같은 통제 사건에서만 **VM Exit**하고 **하이퍼바이저**가 정책을 처리한 뒤 **VM Entry**로 재진입한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **명령어 집합 아키텍처(Instruction Set Architecture, ISA)**: 처리기가 지원하는 명령 형식과 동작의 규약이다.
- **에뮬레이션(Emulation)**: 다른 하드웨어의 명령과 장치 동작을 소프트웨어로 재현하는 방식이다.
- **이진 변환(Binary Translation)**: 게스트 명령을 호스트가 실행할 수 있는 명령으로 바꾸는 방식이다.

</details>

| 가상화 실행 방식 | 하드웨어 지원 가상화 | 에뮬레이션•이진 변환 |
|:---|:---|:---|
| 적용 기준 | 동일 ISA의 VM 직접 실행 | 다른 ISA•장치 동작 재현 |
| 핵심 특징 | 게스트의 비특권 명령 직접 실행 | 명령 해석•변환 후 실행 |
| 한계 | VM Exit•TLB 미스•I/O 중재 | 명령 해석•변환 오버헤드 |

> 요약: 동일 ISA의 VM은 하드웨어 지원으로 직접 실행한다.

#### 한줄 요약

- 호스트와 같은 **ISA**의 게스트는 **하드웨어 가상화**, 다른 ISA의 게스트는 **에뮬레이션**과 **이진 변환**을 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **변환 색인 버퍼(Translation Lookaside Buffer, TLB)**: 최근 가상•물리 주소 변환을 저장하는 고속 캐시이다.
- **TLB 미스**: 필요한 주소 변환이 TLB에 없어 페이지 테이블 순회가 발생하는 상태이다.
- **큰 페이지**: 한 TLB 항목이 더 넓은 메모리 범위를 덮도록 기본보다 큰 주소 단위를 쓰는 페이지이다.
- **비균일 메모리 접근(Non-uniform Memory Access, NUMA)**: 처리기와 메모리 위치에 따라 접근 시간이 달라지는 구조이다.
- **NUMA 노드**: CPU와 가까운 로컬 메모리를 하나의 접근 지연 영역으로 묶은 단위이다.
- **가상 중앙 처리 장치(Virtual CPU, vCPU)**: 물리 CPU 실행 시간을 VM에 제공하는 논리 처리기이다.
- **준가상 장치(Paravirtualized Device)**: 게스트가 하이퍼바이저 인터페이스를 인식해 장치 에뮬레이션 비용을 줄이는 가상 장치이다.
- **인터럽트 병합(Interrupt Coalescing)**: 여러 장치 완료 사건을 묶어 게스트에 전달하여 전환 횟수를 줄이는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 **VM Exit**로 전환 지연 증가 | Exit 원인 계측과 **준가상 장치** 및 **인터럽트 병합** | **vCPU** 처리량 향상 |
| 2단계 페이지 순회로 **TLB 미스** 비용 증폭 | **큰 페이지**와 TLB 지역성 최적화 | 주소 변환 지연 감소 |
| vCPU•메모리가 원격 **NUMA 노드**에 배치돼 접근 지연 증가 | vCPU•메모리•장치의 동일 NUMA 배치 | 원격 메모리 접근 축소 |
| 장치 직접 할당이 DMA 범위를 넓혀 VM 격리 약화 | **IOMMU** 최소 권한과 재할당 전 초기화 | DMA 침해•잔류 상태 방지 |

#### 한줄 요약

- **인터럽트 병합**과 **준가상 장치**로 VM Exit 빈도를 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **장치 직접 할당**: 물리 장치를 특정 VM이 직접 사용하도록 배정하는 방식이다.
- **준가상 드라이버**: 하이퍼바이저를 인식하여 가상 장치의 중재 비용을 줄이는 드라이버이다.
- **가상화 방식 선택 기준**: ISA 호환성과 VM 전환 및 I/O 중재 비용에 따라 실행과 장치 제공 방식을 정하는 기준이다.

</details>

- **가상화 방식 선택 기준**에 따라 동일 ISA는 **하드웨어 가상화**, 다른 ISA는 **에뮬레이션**을 선택하고, I/O 중재 비용은 **준가상 드라이버** 또는 **장치 직접 할당**으로 줄인다.

#### 한줄 요약

- 게스트의 직접 실행 이득이 **VM Exit**와 2단계 주소 변환 및 **가상 입출력** 비용보다 클 때 하드웨어 가상화가 효과적이다.
