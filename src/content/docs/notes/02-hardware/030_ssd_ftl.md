## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플래시 변환 계층(Flash Translation Layer, FTL)**: SSD 컨트롤러 내부 펌웨어로 실행되어 호스트의 논리 블록 주소(LBA)를 낸드 플래시의 물리 주소(PBA)로 매핑하고, 비제자리 갱신, 가비지 컬렉션, 마모도 평준화를 총괄하는 핵심 계층.
- **비제자리 갱신(Out-of-Place Update)**: 낸드 플래시의 직접 덮어쓰기 불가 특성으로 인해 기존 데이터를 제자리에서 수정하지 않고 새로운 빈 페이지에 기록한 후 이전 페이지를 무효(Invalid) 처리하는 기법.
- **쓰기 전 소거(Erase-before-Write)**: 낸드 플래시 셀에 데이터를 새로 프로그래밍(쓰기)하기 전에 반드시 해당 블록 전체를 먼저 소거(Erase)해야 하는 물리적 하드웨어 특성.

</details>

- 정의/개념: 낸드 플래시의 쓰기 전 소거 특성을 은닉하고 호스트의 논리 주소를 물리 주소로 동적 사상하는 **FTL(Flash Translation Layer)**
- 배경/필요성: 기존 낸드의 덮어쓰기 불가 한계로 인한 **LBA-PBA 주소 매핑** 필요성

#### 한줄 요약
- FTL은 낸드 플래시의 물리적 제약을 감추고 고속 블록 스토리지처럼 동작하도록 만드는 SSD 컨트롤러 내부의 핵심 번역 계층이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가비지 컬렉션(Garbage Collection, GC)**: 무효 페이지가 쌓인 희생 블록(Victim Block)을 골라 유효 페이지만 새 블록으로 복사한 뒤, 희생 블록을 소거하여 가용 빈 블록을 확보하는 백그라운드 작업.
- **마모도 평준화(Wear Leveling)**: 낸드 블록 간의 소거 횟수(P/E Cycle) 편차를 줄여 특정 블록의 조기 마모를 방지하고 SSD 전체 수명을 연장하는 알고리즘.
- **쓰기 증폭 계수(Write Amplification Factor, WAF)**: 호스트가 요청한 데이터 쓰기량 대비 가비지 컬렉션 등으로 인해 실제 낸드 플래시에 물리적으로 기록된 총 데이터량의 비율($WAF = \frac{\text{낸드 물리 기록량}}{\text{호스트 논리 쓰기량}}$).

</details>

- 비제자리 갱신: 덮어쓰기가 불가능하므로 항상 새로운 빈 페이지에 데이터를 기록하고 **L2P 매핑 테이블**을 갱신
- 가용 공간 회수: 무효 페이지가 누적된 블록을 선별하여 유효 데이터를 이주시키고 일괄 소거하는 **가비지 컬렉션(GC)** 수행
- 수명 극대화 및 WAF 억제: 동적/정적 **마모도 평준화**를 통해 블록 수명을 균등화하고 **쓰기 증폭 계수(WAF)**를 1에 가깝게 통제

#### 한줄 요약
- FTL은 비제자리 갱신, 가비지 컬렉션, 마모도 평준화를 통해 낸드의 성능과 내구성을 제어한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L2P 매핑 테이블(Logical-to-Physical Mapping Table)**: 호스트 논리 주소(LBA)와 낸드 물리 주소(PBA: 채널/다이/블록/페이지) 간의 변환 정보를 보관하는 메모리 색인 테이블.
- **정전 보호(Power-Loss Protection, PLP)**: 불시 정전 시 탄탈륨 커패시터의 잔류 전력으로 컨트롤러 DRAM 상의 매핑 메타데이터와 쓰기 버퍼 데이터를 낸드에 안전하게 플러시하는 하드웨어 회로.

</details>

```text
[SSD 컨트롤러 서브시스템]
├── [호스트 인터페이스] (NVMe PCIe PHY 계층)
├── [FTL 펌웨어 엔진]
│   ├── [L2P 매핑 엔진] (페이지 레벨 주소 변환)
│   ├── [가비지 컬렉터] (유효 데이터 이주 및 소거)
│   ├── [마모도 평준화기] (동적/정적 마모 균등화)
│   └── [배드 블록 관리기] (결함 블록 검출 및 대체)
├── [온보드 매핑 버퍼] (L2P 매핑 테이블 캐싱 DRAM)
├── [정전 보호 회로 (PLP)] (탄탈륨 커패시터 플러시)
└── [NAND 플래시 어레이] (다채널 다중 다이 낸드)
```

선/분기 의미: 트리 구조(`├──`, `└──`)는 SSD 내부 컨트롤러 하드웨어 및 FTL 펌웨어 엔진의 계층적 포함 관계를 나타냄

| 구성요소 | 소속 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| L2P 매핑 엔진 | FTL 펌웨어 핵심 | 호스트 LBA를 **PBA 물리 주소**로 실시간 변환 | 4KB 페이지 단위 매핑 |
| 가비지 컬렉터 (GC) | FTL 백그라운드 엔진 | 희생 블록 선정 및 **유효 페이지 복사**, 소거 | WAF 및 지연시간 통제 |
| 마모도 평준화기 | FTL 수명 관리 엔진 | 블록별 **소거 횟수 균등 분산** (동적/정적) | SSD 수명 극대화 |
| DRAM 매핑 버퍼 | 컨트롤러 온보드 DRAM | L2P **매핑 테이블 상주** 및 초고속 조회 | 1TB당 1GB 수준 |
| PLP 회로 | SSD 하드웨어 회로 | 불시 정전 시 **더티 데이터 긴급 플러시** | 탄탈륨 커패시터 탑재 |

#### 한줄 요약
- FTL은 L2P 매핑 엔진, 가비지 컬렉터, 마모도 평준화기, 배드 블록 관리기로 구성되며 DRAM 버퍼 및 PLP 회로의 지원을 받는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **희생 블록(Victim Block)**: 가비지 컬렉션 대상 중 무효 페이지 비율이 가장 높고 마모도가 적절하여 소거 대상으로 최종 선정된 물리 블록.

</details>

```text
[호스트의 LBA 쓰기 요청 도달]
                          │
                          ▼
1. FTL: 새로운 빈 물리 페이지(Free Page)에 비제자리 쓰기 수행
                          │
                          ▼
2. FTL: L2P 매핑 테이블 갱신 (새 PBA 사상 및 이전 페이지 무효화)
                          │
                          ▼
3. 가용 빈 블록(Free Blocks) 수가 임계치 이하인지 검사
       ┌──────────────────┴──────────────────┐
 [ 여유 공간 충분 (임계치 초과) ]      [ 여유 공간 부족 (임계치 이하) ]
       │                                     │
       ▼                                     ▼
[즉시 쓰기 완료 응답 반환]             4. 무효율 높은 희생 블록(Victim Block) 선정
       │                                     │
       │                                     ▼
       │                              5. 유효 데이터 새 블록 복사 및 희생 블록 소거(GC)
       └──────────────────┬──────────────────┘
                          │
                          ▼
[가용 공간 확보 후 쓰기 완료 응답 반환]
```

분기 결과: **여유 빈 블록** 보유 시 즉시 응답하나, **블록 고갈** 시 전경 GC 발생으로 쓰기 지연시간이 증가함

#### 한줄 요약
- 빈 페이지에 쓰고 매핑을 갱신하며, 가용 블록이 부족해지면 희생 블록의 유효 데이터를 옮기고 소거하는 GC를 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 매핑(Page-Level Mapping)**: 페이지 단위(4KB)로 주소를 매핑하여 임의 쓰기 성능을 극대화하는 방식.
- **블록 매핑(Block-Level Mapping)**: 블록 단위(수 MB)로 매핑하여 매핑 테이블 크기를 줄이는 방식.
- **하이브리드 매핑(Hybrid/Log Mapping)**: 데이터 블록과 로그 블록을 조합하여 메모리와 성능을 절충한 방식.

</details>

| 매핑 방식 | 페이지 매핑 (Page-Level) | 블록 매핑 (Block-Level) | 하이브리드 매핑 (Log Block) |
|:---|:---|:---|:---|
| 매핑 단위 | **4KB 페이지** 단위 | **수 MB 블록** 단위 | 데이터 블록/로그 페이지 혼합 |
| 임의 쓰기 성능 | **최고** (복사 오버헤드 없음) | 매우 낮음 (블록 전체 복사) | 중간 (로그 병합 오버헤드) |
| 매핑 테이블 크기 | 큼 (1TB당 **1GB DRAM** 필요) | **매우 작음** (DRAM 불필요) | 작음 (로그 블록 매핑만 유지) |
| 현대 채택 여부 | 고성능 SSD **표준 채택** | 거의 미사용 (특수 임베디드) | 저가형 DRAM-less 적용 |

#### 한줄 요약
- 임의 쓰기 성능과 수명 관리를 위해 현대 고성능 SSD는 페이지 레벨 매핑(Page-Level Mapping)을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오버 프로비저닝(Over-Provisioning, OP)**: 전체 낸드 용량의 일부(7~28%)를 사용자에게 숨기고 GC 버퍼 및 예비 블록으로 할당하는 기법.
- **TRIM(Deallocate)**: OS가 파일 삭제 시 해당 LBA가 무효화되었음을 SSD에 미리 통지하여 GC 시 불필요한 유효 데이터 복사를 차단하는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전경 GC 쓰기 지연 | **오버 프로비저닝(OP)** 및 백그라운드 GC | 전경 GC 억제 및 지속 성능 향상 |
| 무효 데이터 복사 누적 | OS **TRIM(Deallocate)** 명령어 활성화 | 불필요한 GC 복사 제거 및 **WAF 절감** |
| 불시 정전 매핑 유실 | 커패시터 기반 **정전 보호(PLP)** 회로 적용 | 메타데이터 100% **안전 플러시** 보장 |

#### 한줄 요약
- 실무에서는 OP 공간 확보와 TRIM 연동으로 WAF와 GC 지연을 잡고, PLP 회로로 정전 시 무결성을 확보한다.

## Ⅶ. 결론

- 쓰기 패턴 분석 기반 **L2P 페이지 매핑** 및 **하드웨어 PLP** 체계 구축

#### 한줄 요약
- FTL은 낸드 플래시의 성능과 수명을 완성하는 핵심 소프트웨어이며, OP와 TRIM, ZNS를 통해 엔터프라이즈 성능을 달성한다.
