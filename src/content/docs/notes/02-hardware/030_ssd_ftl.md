## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플래시 변환 계층(Flash Translation Layer, FTL)**: SSD 컨트롤러 내부 펌웨어로 실행되어 호스트의 논리 블록 주소(LBA)를 낸드 플래시의 물리 주소(PBA)로 매핑하고, 비제자리 갱신, 가비지 컬렉션, 마모도 평준화를 총괄하는 핵심 계층.
- **비제자리 갱신(Out-of-Place Update)**: 낸드 플래시의 직접 덮어쓰기 불가 특성으로 인해 기존 데이터를 제자리에서 수정하지 않고 새로운 빈 페이지에 기록한 후 이전 페이지를 무효(Invalid) 처리하는 기법.
- **쓰기 전 소거(Erase-before-Write)**: 낸드 플래시 셀에 데이터를 새로 프로그래밍(쓰기)하기 전에 반드시 해당 블록 전체를 먼저 소거(Erase)해야 하는 물리적 하드웨어 특성.

</details>

- 정의/개념: 호스트의 논리 블록 주소(LBA)를 낸드 플래시의 물리 블록 주소(PBA)로 매핑하고 비제자리 갱신, 가비지 컬렉션, 마모도 평준화를 총괄하는 **SSD 컨트롤러 펌웨어 계층**
- 배경/필요성: 낸드 플래시의 쓰기 전 소거(Erase-before-Write) 물리적 제약 및 덮어쓰기 불가 한계 극복과 블록 소거 횟수 편차에 따른 조기 마모 방지

#### 한줄 요약
- FTL은 낸드 플래시의 물리적 제약을 감추고 고속 블록 스토리지처럼 동작하도록 만드는 SSD 컨트롤러 내부의 핵심 번역 계층이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가비지 컬렉션(Garbage Collection, GC)**: 무효 페이지가 쌓인 희생 블록(Victim Block)을 골라 유효 페이지만 새 블록으로 복사한 뒤, 희생 블록을 소거하여 가용 빈 블록을 확보하는 백그라운드 작업.
- **마모도 평준화(Wear Leveling)**: 낸드 블록 간의 소거 횟수(P/E Cycle) 편차를 줄여 특정 블록의 조기 마모를 방지하고 SSD 전체 수명을 연장하는 알고리즘.
- **쓰기 증폭 계수(Write Amplification Factor, WAF)**: 호스트가 요청한 데이터 쓰기량 대비 가비지 컬렉션 등으로 인해 실제 낸드 플래시에 물리적으로 기록된 총 데이터량의 비율($WAF = \frac{\text{낸드 물리 기록량}}{\text{호스트 논리 쓰기량}}$).

</details>

- 논리 주소를 물리 주소로 동적 변환하여 빈 페이지에 순차 기록하는 **비제자리 갱신(Out-of-Place Update)** 수행
- 무효 페이지가 누적된 희생 블록을 회수하여 가용 공간을 확보하는 백그라운드 **가비지 컬렉션(GC)** 제어
- 블록 간 소거 횟수를 균등하게 분산시키는 **마모도 평준화(Wear Leveling)**를 통해 SSD 수명 연장 및 WAF 최소화

#### 한줄 요약
- FTL은 비제자리 갱신, 가비지 컬렉션, 마모도 평준화를 통해 낸드의 성능과 내구성을 제어한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L2P 매핑 테이블(Logical-to-Physical Mapping Table)**: 호스트 논리 주소(LBA)와 낸드 물리 주소(PBA: 채널/다이/블록/페이지) 간의 변환 정보를 보관하는 메모리 색인 테이블.
- **정전 보호(Power-Loss Protection, PLP)**: 불시 정전 시 탄탈륨 커패시터의 잔류 전력으로 컨트롤러 DRAM 상의 매핑 메타데이터와 쓰기 버퍼 데이터를 낸드에 안전하게 플러시하는 하드웨어 회로.

</details>

```text
+-------------------------------------------------------------+
|              호스트 시스템 (Host File System / NVMe 드라이버) |
+-------------------------------------------------------------+
                               | LBA 기반 읽기 / 쓰기 / TRIM 명령
                               v
+-------------------------------------------------------------+
|               SSD 컨트롤러 & FTL 펌웨어 엔진                 |
|  +-------------------------------------------------------+  |
|  |           L2P 주소 매핑 엔진 (Page Mapping)           |  |
|  +-------------------------------------------------------+  |
|  | 가비지 컬렉터 (GC)     | 마모도 평준화기 (Wear Leveler)|  |
|  | 배드 블록 관리기       | 오버 프로비저닝 (OP) 관리기   |  |
|  +-------------------------------------------------------+  |
|  | 온보드 DRAM 매핑 캐시   | 정전 보호 커패시터 회로 (PLP)|  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
                               | 채널/다이 병렬 인터페이스 (PBA)
                               v
+-------------------------------------------------------------+
|               NAND 플래시 메모리 다이 어레이                |
|  +-----------------------+       +-----------------------+  |
|  | Flash Die 0 (채널 0)  |  ...  | Flash Die N (채널 N)  |  |
|  | [블록 0: 페이지 0~N]  |       | [블록 M: 페이지 0~N]  |  |
|  +-----------------------+       +-----------------------+  |
+-------------------------------------------------------------+
```

선의 의미: 실선 화살표는 호스트 논리 주소(LBA) 요청이 FTL 엔진을 통과하여 물리 주소(PBA)로 변환된 후 다채널 NAND 다이 어레이로 전달되는 데이터 흐름을 나타냄

| 구성요소 | 책임 |
|:---|:---|
| L2P 매핑 엔진 | 호스트 LBA를 물리 페이지 **PBA로 변환**하고 매핑 테이블 실시간 갱신 |
| 가비지 컬렉터 (GC) | 희생 블록 선정 및 유효 페이지 이주를 통해 **가용 빈 블록 회수** |
| 마모도 평준화기 | 핫/콜드 블록 교체를 통해 블록별 **소거 횟수 균등화** 달성 |
| 온보드 DRAM 버퍼 | **L2P 매핑 테이블 캐싱** 및 고속 쓰기 버퍼링 제공 |
| 정전 보호 회로 (PLP) | 전원 차단 시 보조 전력으로 **더티 메타데이터 안전 플러시** |

#### 한줄 요약
- FTL은 L2P 매핑 엔진, 가비지 컬렉터, 마모도 평준화기, 배드 블록 관리기로 구성되며 DRAM 버퍼 및 PLP 회로의 지원을 받는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **희생 블록(Victim Block)**: 가비지 컬렉션 대상 중 무효 페이지 비율이 가장 높고 마모도가 적절하여 소거 대상으로 최종 선정된 물리 블록.

</details>

```text
+-------------------------------------------------------------+
|              호스트의 LBA 데이터 쓰기 명령 도달              |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       1. 가용 빈 물리 페이지 탐색 및 비제자리 쓰기          |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       2. DRAM L2P 매핑 테이블 갱신 및 이전 페이지 무효화    |
+-------------------------------------------------------------+
                               |
                               v
                +-------------------------------+
                |     3. 가용 블록 임계치 판정   |
                +-------------------------------+
                       |                 |
              [여유 블록 충분]           | [임계치 이하 고갈]
                       |                 v
                       | +-------------------------------+
                       | | 4. GC 발동: 희생 블록 선정    |
                       | +-------------------------------+
                       |                 |
                       |                 v
                       | +-------------------------------+
                       | | 5. 유효 데이터 복사 및 소거   |
                       | +-------------------------------+
                       v                 |
+-----------------------+               |
| 쓰기 완료 즉시 응답   |               |
+-----------------------+               |
                       |                 |
                       +--------+--------+
                                v
+-------------------------------------------------------------+
|            가용 풀 회수 완료 및 호스트 쓰기 완료 반환        |
+-------------------------------------------------------------+
```

분기 결과: **가용 빈 블록**이 충분하면 수십 마이크로초 내에 쓰기가 즉시 완료되나, **빈 블록 고갈** 시 실시간 전경 GC가 발생하여 유효 페이지 복사 및 블록 소거 지연(수 밀리초)이 부가됨

**동작 원리**

1. **가용 빈 물리 페이지 탐색**: FTL이 현재 활성 열린 블록(Open Block)에서 연속된 빈 물리 페이지를 할당하여 데이터를 비제자리 방식으로 직접 기록
2. **L2P 매핑 갱신 및 무효화**: DRAM 상의 L2P 테이블을 갱신하여 새 PBA를 매핑하고, 이전 데이터가 저장되어 있던 물리 페이지를 무효(Invalid) 상태로 플래깅
3. **가용 블록 임계치 검사**: 프리 블록 풀(Free Block Pool)의 잔여 블록 수가 설정된 최소 임계값 미만으로 하락했는지 검사
4. **희생 블록 선정 알고리즘 가동**: 가용 블록이 부족한 경우 무효 페이지 비율이 가장 높고 소거 횟수가 적은 물리 블록을 희생 블록(Victim Block)으로 선정
5. **유효 페이지 이주 및 블록 소거**: 희생 블록 내 잔류 유효 페이지만을 새 블록으로 복사한 후, 희생 블록 전체를 고전압으로 소거하여 완전히 깨끗한 프리 블록으로 회수

#### 한줄 요약
- 빈 페이지에 쓰고 매핑을 갱신하며, 가용 블록이 부족해지면 희생 블록의 유효 데이터를 옮기고 소거하는 GC를 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **페이지 매핑(Page-Level Mapping)**: 페이지 단위(4KB)로 주소를 매핑하여 임의 쓰기 성능을 극대화하는 방식.
- **블록 매핑(Block-Level Mapping)**: 블록 단위(수 MB)로 매핑하여 매핑 테이블 크기를 줄이는 방식.
- **하이브리드 매핑(Hybrid/Log Mapping)**: 데이터 블록과 로그 블록을 조합하여 메모리와 성능을 절충한 방식.

</details>

| FTL 주소 매핑 기법 | 페이지 매핑 (Page-Level) | 블록 매핑 (Block-Level) | 하이브리드 매핑 (Hybrid/Log) |
|:---|:---|:---|:---|
| 적용 기준 | 초고성능 임의 쓰기 및 일반 NVMe SSD 환경 | 메모리 용량이 극도로 제약된 저가형 임베디드 장치 | DRAM 용량과 쓰기 성능의 절충이 필요한 환경 |
| 핵심 특징 | **4KB 페이지 단위** 정밀 매핑으로 임의 쓰기 극대화 | **수 MB 블록 단위** 매핑으로 DRAM 메모리 소모 최소화 | 데이터 블록과 로그 블록을 혼용하여 매핑 |
| 한계 | 전체 용량의 약 0.1%에 달하는 대용량 **DRAM 매핑 버퍼** 필요 | 단 1개 페이지 수정 시에도 블록 전체를 복사하는 **극심한 오버헤드** | 로그 블록 소진 시 발생하는 복잡한 풀 머지(Merge) 지연 |

#### 한줄 요약
- 임의 쓰기 성능과 수명 관리를 위해 현대 고성능 SSD는 페이지 레벨 매핑(Page-Level Mapping)을 표준으로 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오버 프로비저닝(Over-Provisioning, OP)**: 전체 낸드 용량의 일부(7~28%)를 사용자에게 숨기고 GC 버퍼 및 예비 블록으로 할당하는 기법.
- **TRIM(Deallocate)**: OS가 파일 삭제 시 해당 LBA가 무효화되었음을 SSD에 미리 통지하여 GC 시 불필요한 유효 데이터 복사를 차단하는 명령어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 전경 GC 발생 시 사용자 I/O 멈춤 및 긴 꼬리 지연 | **오버 프로비저닝(OP)** 및 백그라운드 선제적 GC | GC 빈도 분산 및 지속적인 일관 쓰기 IOPS 보장 |
| OS 파일 삭제 후에도 NAND에 무효 데이터 방치되어 WAF 증가 | **NVMe TRIM(Deallocate)** 명령어 실시간 연동 | 무효 페이지 사전 마킹으로 GC 복사량 절감 및 **WAF 축소** |
| 갑작스러운 전원 차단 시 DRAM L2P 메타데이터 증발 | 탄탈륨 커패시터 기반 **정전 보호 회로(PLP)** 실장 | 전원 차단 후 잔류 전력으로 **안전 플러시** 보장 |

#### 한줄 요약
- 실무에서는 OP 공간 확보와 TRIM 연동으로 WAF와 GC 지연을 잡고, PLP 회로로 정전 시 무결성을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **존 네임스페이스(Zoned Namespaces, ZNS)**: 호스트가 데이터 배치 순서를 제어하여 FTL의 가비지 컬렉션 오버헤드와 OP 공간 필요성을 획기적으로 줄이는 표준 규격.
- **호스트 메모리 버퍼(Host Memory Buffer, HMB)**: DRAM 없는 보급형 SSD가 호스트 시스템 메모리의 일부를 매핑 캐시로 활용하는 NVMe 표준 기술.

</details>

낸드 플래시의 물리적 한계를 은닉하고 초고속 스토리지 I/O를 실현하는 핵심 펌웨어 계층이며, 향후 엔터프라이즈 환경에서 ZNS 및 대규모 CXL 메모리 풀링과 연계된 구조적 진화.

#### 한줄 요약
- FTL은 낸드 플래시의 성능과 수명을 완성하는 핵심 소프트웨어이며, OP와 TRIM, ZNS를 통해 엔터프라이즈 성능을 달성한다.
