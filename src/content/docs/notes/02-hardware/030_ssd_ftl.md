## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플래시 변환 계층(Flash Translation Layer, FTL)**: SSD 컨트롤러 내부에서 호스트 파일 시스템의 논리 주소(LBA)를 낸드 플래시의 물리 주소(PBA)로 동적 변환하고 수명을 관리하는 펌웨어.
- **비제자리 갱신(Out-of-Place Update)**: 낸드 플래시의 덮어쓰기 불가 특성으로 인해 기존 위치를 지우지 않고 새로운 빈 페이지에 기록 후 기존 페이지를 무효화하는 기법.
- **쓰기 전 소거(Erase-before-Write)**: 낸드 플래시는 읽기/쓰기가 페이지(4~16KB) 단위로 동작하지만, 데이터 삭제는 블록(수 MB) 단위로만 수행 가능한 하드웨어 특성.

</details>

- 정의/개념: SSD 컨트롤러 내부에서 호스트 파일 시스템의 논리 주소(LBA)를 낸드 플래시의 물리 주소(PBA)로 동적 변환하고 비제자리 갱신, GC, 마모도 평준화를 총괄하는 펌웨어 계층
- 배경/필요성: 쓰기 전 소거(Erase-before-Write)와 입출력 단위 불일치(Read/Write는 Page, Erase는 Block)라는 **낸드 플래시의 물리적 제약을 OS로부터 투명하게 은닉**

#### 한줄 요약

- 논리-물리 주소 변환(LBA $\to$ PBA)과 **비제자리 갱신, GC, 마모도 평준화** 수행

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가비지 컬렉션(Garbage Collection, GC)**: 무효 페이지가 누적된 희생 블록(Victim Block)에서 유효 페이지를 새 블록으로 복사 후 희생 블록 전체를 소거하여 빈 공간을 확보하는 작업.
- **마모도 평준화(Wear Leveling)**: 낸드 블록의 P/E Cycle(소거 수명) 편차를 줄이기 위해 모든 블록이 균등하게 소거되도록 분산하는 수명 관리 알고리즘.
- **쓰기 증폭 계수(Write Amplification Factor, WAF)**: 호스트가 요청한 쓰기 데이터량 대비 GC 유효 데이터 복사 등으로 인해 실제 낸드에 물리적으로 기록된 데이터량의 비율 ($\text{WAF} = \frac{\text{NAND Write}}{\text{Host Write}} \ge 1.0$).

</details>

- **비제자리 갱신(Out-of-Place Update)**을 적용하여 새 빈 페이지에 즉시 기록하고 기존 페이지는 무효(Invalid) 상태로 마킹
- 백그라운드 **가비지 컬렉션(GC)**을 통해 무효 페이지가 다수 포함된 희생 블록을 일괄 소거하여 프리 블록 풀 회수
- GC 수행 중 유효 데이터 복사 오버헤드로 인해 발생하는 **쓰기 증폭(WAF)** 및 응답 지연을 제어하는 최적화 필수

#### 한줄 요약

- **비제자리 갱신·가비지 컬렉션(GC)·마모도 평준화(Wear Leveling)**를 통한 수명 연장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L2P 매핑 테이블(Logical-to-Physical Mapping Table)**: 호스트 LBA 번지를 낸드 플래시 다이/채널/블록/페이지 번호(PBA)로 변환하는 핵심 룩업 테이블.
- **PLP(Power-Loss Protection)**: 예기치 못한 정전 시 보조 탄탈륨 커패시터 전력으로 컨트롤러 DRAM 캐시 데이터를 낸드에 안전하게 플러시하는 회로.

</details>

```text
[ SSD 컨트롤러 내부 FTL 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 인터페이스 (NVMe / PCIe Protocol Engine)             │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 플래시 변환 계층 (FTL 펌웨어 모듈)                          │
│  ├─ L2P 주소 매핑 엔진 (Page-Level Mapping Engine)          │
│  ├─ 가비지 컬렉터 (Victim Selection & Valid Page Copy)      │
│  ├─ 마모도 평준화기 (Dynamic & Static Wear Leveling)        │
│  ├─ 배드 블록 관리기 (Bad Block Management)                 │
│  └─ 전력 차단 보호기 (PLP & Journaling Recovery)            │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 온보드 DRAM / SRAM (L2P 매핑 테이블 및 쓰기 버퍼 캐시)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 낸드 플래시 제어기 (다중 채널/다중 다이 병렬 플래시 배열)    │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 호스트 인터페이스, FTL 핵심 엔진(L2P 매핑/GC/Wear Leveling/PLP) 및 낸드 플래시 제어기 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 논리 물리 매핑 엔진 | 논리 페이지 번호(LBA)와 실제 물리 페이지 주소(PBA) 간의 고속 매핑 관리 |
| 가비지 컬렉터 | 낭비된 희생 블록 선택, 유효 페이지 이주 및 물리적 소거 수행 |
| 마모도 평준화기 | 낸드 블록 전체의 소거 횟수 균등 분산 스케줄링 관리 |
| 전력 차단 보호기 | 예기치 않은 정전 시 기록 데이터 및 매핑 메타데이터 안전 보존 |

#### 한줄 요약

- **L2P 매핑 테이블·가비지 컬렉터·마모도 평준화기·PLP 전력 보호 회로** 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Victim Block(희생 블록)**: 가비지 컬렉션 대상으로 선정된 무효 페이지 비율이 가장 높은 낸드 블록.

</details>

```text
[ 호스트 LBA 쓰기 요청 도달 ]
               │
               ▼
 [ 1. 빈 물리 페이지(PBA)에 신규 데이터 기록 ]
               │
               ▼
 [ 2. L2P 매핑 테이블 갱신 (LBA ──> 신규 PBA) ]
               │
               ▼
 [ 3. 이전 PBA 페이지 상태를 Invalid로 마킹 ]
               │
     [ 여유 클린 블록 개수 임계치 미달 검사 ]
               │
     ┌─────────┴─────────┐
     ▼ [정상 여유]       ▼ [임계치 미달 (GC 필요)]
 [ 쓰기 완료 응답 ]  [ 4. 백그라운드 Garbage Collection 구동 ]
                         ├─ 무효 페이지 최다 희생 블록 선정
                         ├─ 유효 페이지를 새 클린 블록으로 복사
                         └─ 희생 블록 전체 물리적 Erase 수행
```

**동작 원리**

1. **신규 기록**: 비어있는 새 물리 페이지(PBA)를 할당하여 데이터를 낸드에 쓰기 수행
2. **매핑 갱신**: 온칩 DRAM의 L2P 테이블에서 해당 LBA의 포인터를 신규 PBA로 업데이트
3. **이전 무효화**: 이전에 해당 LBA를 가리키던 이전 물리 페이지는 무효(Invalid) 상태로 변경
4. **가비지 컬렉션**: 여유 블록이 임계치 미만으로 떨어지면 희생 블록을 선택하여 유효 페이지만 복사 후 블록 일괄 소거

#### 한줄 요약

- 신규 페이지 기록 $\to$ **L2P 매핑 갱신 및 기존 PBA 무효화 $\to$ 임계치 도달 시 GC 구동**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **L2P Mapping 방식 비교**:
  - Page-Level: 4KB 단위 세밀한 매핑, 최고 임의 쓰기 성능, DRAM 용량 소모(1TB당 ~1GB)
  - Block-Level: 수 MB 블록 단위 매핑, 메모리 소모 극소, 임의 쓰기 시 극심한 오버헤드
  - Hybrid: 블록 매핑 기본에 소량 로그 블록만 페이지 매핑

</details>

| 주소 매핑 방식 | 페이지 매핑 (Page-Level) | 블록 매핑 (Block-Level) | 하이브리드 매핑 (Hybrid/Log) |
|:---|:---|:---|:---|
| 매핑 단위 및 구조 | 4KB 페이지 단위 개별 매핑 (LPN $\to$ PPN) | 1~4MB 블록 단위 매핑 (LBN $\to$ PBN) | 블록 매핑 기본에 소량의 로그 블록만 페이지 매핑 |
| 성능 및 WAF | 4KB 랜덤 쓰기 성능 극대화, 쓰기 증폭(WAF) 최소화 | 랜덤 쓰기 시 블록 복사/소거 병합으로 성능 최악 | 순차 쓰기는 우수하나 로그 블록 풀 소진 시 성능 저하 |
| 한계 및 메모리 소모 | 1TB당 약 1GB의 대용량 DRAM/HMB 메모리 요구 | 메모리 소모 극히 미미하나 랜덤 쓰기 처리 불가 | 로그 블록 병합(Merge) 오버헤드 및 제어 복잡도 증가 |

#### 한줄 요약

- 현대 고성능 SSD는 DRAM/HMB 기반 **페이지 매핑(Page-Level Mapping) 표준 채택**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Over-Provisioning(OP)**: 전체 낸드 용량의 7~28%를 호스트에 노출하지 않고 FTL의 GC 전용 공간으로 예약하여 WAF를 낮추고 수명을 연장하는 기법.
- **TRIM (Deallocate)**: OS가 파일 삭제 시 해당 LBA가 무효화되었음을 FTL에 알려 불필요한 GC 복사를 방지하는 명령.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 호스트 쓰기 폭주 시 즉각적인 전경 가비지 컬렉션 발동으로 인한 지연 상승 | 워크로드 특성에 맞춘 **초과 예비 공간** 넉넉한 확보 및 운영체제 **트림 명령** 연동 | 펌웨어 여유 블록 조기 확보 및 지연을 유발하는 전경 수집 빈도 강력 억제 |
| 소규모 무작위 쓰기 지속 시 심각한 쓰기 증폭 폭증으로 낸드 수명 단축 | 계층 내 데이터 쓰기 버퍼 능동 집계 및 정밀한 페이지 매핑 기술 상시 구동 | 무의미한 낸드 쓰기 증폭 원천 억제 및 물리적 소거 수명 연장 |
| 특정 읽기 전용 데이터 적재 구역의 마모율 불균형에 따른 셀 조기 불량 | **정적 마모도 평준화** 가동을 통한 차가운 정지 데이터의 정기적 강제 이주 | 전체 낸드 칩 단위의 물리적 블록 지우기 횟수 수명 완벽 균등화 |
| 불시 정전 시 임시 메모리 상의 매핑 테이블 유실 및 치명적인 데이터 파손 | 기판 전용 방전 커패시터 탑재 및 영구 플래시 구역의 매핑 저널 즉각 회복 가동 | 불시 정전 후 재부팅 시 주소 매핑 테이블 무결성 100% 복구 보장 |

#### 한줄 요약

- **Over-Provisioning(OP)·TRIM 명령·정적 마모도 평준화·PLP 탄탈륨 커패시터**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ZNS(Zoned Namespaces)**: FTL의 GC 오버헤드를 제거하기 위해 호스트 애플리케이션이 순차 쓰기 존(Zone) 단위로 낸드에 직접 기록하여 WAF를 1.0에 근접시키는 차세대 스토리지 기술.

</details>

- 데이터센터 엔터프라이즈 환경에서 **7~28% OP 확보, Page-Level 매핑, 하드웨어 PLP 탑재 SSD 표준 채택**

#### 한줄 요약

- **WAF 최소화, 꼬리 지연(p99) 억제, 정전 무결성**을 위한 FTL 최적화
