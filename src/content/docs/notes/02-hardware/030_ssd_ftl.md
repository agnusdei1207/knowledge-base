## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플래시 변환 계층(Flash Translation Layer, FTL)**: SSD 컨트롤러가 호스트 논리 주소(LBA)를 낸드 플래시의 물리 위치로 변환하고 수명·공간을 관리하는 펌웨어·제어 계층.
- **비제자리 갱신(Out-of-Place Update)**: 낸드 플래시의 덮어쓰기 불가 특성으로 인해 기존 위치를 지우지 않고 새로운 빈 페이지에 기록 후 기존 페이지를 무효화하는 기법.
- **쓰기 전 소거(Erase-before-Write)**: 낸드 플래시는 페이지 단위로 읽기·프로그램하고 블록 단위로 소거하는 특성. 실제 단위 크기는 제품과 세대에 따라 다르다.

</details>

- 정의/개념: 호스트 LBA를 낸드 PBA로 사상하고 **가비지 컬렉션**·**마모도 평준화**를 수행하는 SSD 제어 계층
- 배경/필요성: 낸드는 페이지 덮어쓰기가 불가능하고 블록을 먼저 소거해야 해 **블록 장치 쓰기 의미론** 직접 제공 불가

#### 한줄 요약

- FTL은 새 페이지에 기록한 뒤 주소 매핑을 바꾸고, 무효 페이지를 회수하면서 블록 수명을 분산한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가비지 컬렉션(Garbage Collection, GC)**: 무효 페이지가 누적된 희생 블록(Victim Block)에서 유효 페이지를 새 블록으로 복사 후 희생 블록 전체를 소거하여 빈 공간을 확보하는 작업.
- **마모도 평준화(Wear Leveling)**: 낸드 블록의 P/E Cycle(소거 수명) 편차를 줄이기 위해 모든 블록이 균등하게 소거되도록 분산하는 수명 관리 알고리즘.
- **쓰기 증폭 계수(Write Amplification Factor, WAF)**: 호스트 쓰기량 대비 실제 낸드에 기록된 데이터량의 비율. GC·메타데이터·정렬 방식이 WAF를 높이며, 압축·중복 제거 같은 기능을 제외한 일반적 정의에서는 1 이상으로 본다.

</details>

- **비제자리 갱신**으로 새 빈 페이지에 기록 후 기존 페이지 무효화
- **가비지 컬렉션(GC)** 을 통한 희생 블록 소거로 가용 저장 공간 확보
- **마모도 평준화**와 WAF 제어로 블록 수명 편차·내부 쓰기량 감소

#### 한줄 요약

- 새 페이지 기록이 누적되면 GC가 유효 페이지를 옮겨 빈 블록을 만들고, 마모도 평준화가 소거 횟수를 분산한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L2P 매핑 테이블(Logical-to-Physical Mapping Table)**: 호스트 LBA 번지를 낸드 플래시 다이/채널/블록/페이지 번호(PBA)로 변환하는 핵심 룩업 테이블.
- **PLP(Power-Loss Protection)**: 예기치 못한 정전 시 보조 탄탈륨 커패시터 전력으로 컨트롤러 DRAM 캐시 데이터를 낸드에 안전하게 플러시하는 회로.

</details>

```text
[ SSD 컨트롤러 내부 FTL 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 호스트 인터페이스 (NVMe / PCIe Protocol Engine)             │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 플래시 변환 계층 (FTL 펌웨어 모듈)                          │
│  ├─ L2P 주소 매핑 엔진 (Page-Level Mapping Engine)          │
│  ├─ 가비지 컬렉터 (Victim Selection & Valid Page Copy)      │
│  ├─ 마모도 평준화기 (Dynamic & Static Wear Leveling)        │
│  └─ 배드 블록 관리기 (Bad Block Management)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 온보드 DRAM / SRAM (L2P 매핑 테이블 및 쓰기 버퍼 캐시)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ 낸드 플래시 제어기 (다중 채널/다중 다이 병렬 플래시 배열)    │
└─────────────────────────────────────────────────────────────┘
              PLP 회로 ── 컨트롤러·매핑 메타데이터 보호
```

선의 의미: 호스트 인터페이스, FTL 핵심 엔진(L2P 매핑/GC/Wear Leveling/PLP) 및 낸드 플래시 제어기 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| L2P 매핑 엔진 | 호스트 LBA와 낸드 PBA 간 매핑 관리 |
| 가비지 컬렉터 | 낭비된 희생 블록 선택, 유효 페이지 이주 및 물리적 소거 수행 |
| 마모도 평준화기 | 낸드 블록 전체의 소거 횟수 **균등 분산** 스케줄링 관리 |
| 배드 블록 관리기 | 결함 블록 검출 및 예비 블록 **대체 매핑** |
| 전력 차단 보호기 | 예기치 않은 정전 시 기록 데이터 및 매핑 메타데이터 안전 보존 |

#### 한줄 요약

- FTL은 주소 매핑·공간 회수·수명 분산을 맡고, PLP는 정전 시 진행 중 쓰기와 매핑 메타데이터를 보호한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Victim Block(희생 블록)**: 가비지 컬렉션 대상으로 선정된 낸드 블록. 무효 페이지 비율 외에도 마모도·온도·지연 목표가 선택 기준에 반영될 수 있다.

</details>

```text
[ 호스트 LBA 쓰기 요청 도달 ]
               │
               ▼
 [ 1. 신규 물리 페이지 기록 ]
               │
               ▼
 [ 2. L2P 매핑 테이블 갱신 ]
               │
               ▼
 [ 3. 이전 페이지 무효화 ]
               │
     [ 여유 클린 블록 개수 임계치 미달 검사 ]
               │
     ┌─────────┴─────────┐
     ▼ [정상 여유]       ▼ [임계치 미달 (GC 필요)]
 [ 쓰기 완료 응답 ]  [ 4. 가비지 컬렉션 구동 ]
                         ├─ 무효 페이지 최다 희생 블록 선정
                         ├─ 유효 페이지를 새 클린 블록으로 복사
                         └─ 희생 블록 전체 물리적 Erase 수행
```

**동작 원리**

1. **신규 물리 페이지 기록**: 비어있는 새 물리 페이지를 할당해 데이터 기록
2. **L2P 매핑 테이블 갱신**: 온칩 DRAM 매핑 테이블에서 신규 PBA로 갱신
3. **이전 페이지 무효화**: 기존 물리 페이지 상태를 무효(Invalid)로 마킹
4. **가비지 컬렉션 구동**: 여유 블록 부족 시 희생 블록 선정 및 유효 복사 후 소거

#### 한줄 요약

- 새 페이지 기록과 L2P 갱신이 기존 페이지를 무효화하며, 빈 블록이 부족해지면 GC가 공간을 회수한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **L2P Mapping 방식 비교**: Page-Level은 세밀한 임의 쓰기 처리를 돕지만 매핑 저장 공간이 크고, Block-Level은 매핑 공간을 줄이는 대신 임의 갱신 비용이 커질 수 있으며, Hybrid는 두 특성을 절충한다.

</details>

| FTL 매핑 방식 | 페이지 매핑 (Page-Level) | 블록 매핑 (Block-Level) | 하이브리드 매핑 (Hybrid/Log) |
|:---|:---|:---|:---|
| 적용 기준 | 임의 쓰기 성능이 중요하고 매핑 메모리 확보 가능 | 순차 쓰기 중심이며 매핑 메모리 최소화 필요 | 매핑 메모리와 임의 쓰기 성능 절충 |
| 핵심 특징 | 페이지 단위 주소 매핑으로 임의 쓰기 처리 유연성 확보 | 블록 단위 매핑으로 매핑 테이블 저장 공간 절감 | 데이터 블록과 로그 블록을 조합해 절충 |
| 한계 | 대용량 매핑 테이블 저장·캐시 자원 필요 | 임의 갱신에서 복사·병합 비용 증가 가능 | 로그 블록 관리·병합·GC 복잡도 증가 |

#### 한줄 요약

- 페이지 매핑은 임의 쓰기에 유리하고, 블록·하이브리드 매핑은 매핑 메모리를 줄이는 대신 병합 비용을 감수한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Over-Provisioning(OP)**: 일부 낸드 용량을 호스트에 노출하지 않고 GC·마모도 관리의 여유 공간으로 남겨 WAF와 지연을 완화하는 기법.
- **TRIM (Deallocate)**: OS가 더 이상 필요하지 않은 LBA 범위를 SSD에 알려 GC가 해당 데이터를 유효 데이터로 복사하지 않도록 돕는 명령.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 빈 블록 부족으로 전경 GC가 발생해 꼬리 지연 증가 | **OP** 확보·**TRIM** 연동 | 전경 GC 빈도·유효 페이지 복사량 감소 |
| 소규모 임의 쓰기로 **WAF** 증가 | 쓰기 버퍼 집계·페이지 매핑 적용 | 낸드 기록량·소거 수명 소모 감소 |
| 차가운 데이터가 블록을 점유해 마모 편차 증가 | **정적 마모도 평준화**로 데이터 재배치 | 블록별 소거 횟수 편차 완화 |
| 불시 정전 시 임시 메모리 상의 매핑 테이블 유실 | 전원 차단 보호와 영구 매핑 저널·복구 절차 적용 | 설계된 보호 범위에서 메타데이터·진행 중 쓰기 손상 위험 감소 |

#### 한줄 요약

- OP와 TRIM은 GC 여유를 늘리고, 마모도 평준화는 블록 수명 편차를 줄이며, PLP와 저널은 정전 복구 범위를 보장한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ZNS(Zoned Namespaces)**: 호스트가 존 단위의 순차 쓰기 규칙을 지켜 데이터 배치와 회수를 협력하도록 하는 NVMe 기능. FTL 관리 부담과 WAF를 줄일 수 있지만 완전히 제거하지는 않는다.

</details>

- 임의 쓰기 SSD는 **페이지·하이브리드 매핑**과 OP·TRIM으로 WAF를 관리하고, 순차 배치를 제어할 수 있는 워크로드는 **ZNS**로 FTL의 배치·GC 부담을 추가 완화

#### 한줄 요약

- FTL은 평균 처리량보다 WAF·꼬리 지연·정전 복구 범위를 함께 측정해 매핑과 GC 정책을 정해야 한다.
