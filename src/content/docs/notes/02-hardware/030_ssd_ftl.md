## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **플래시 변환 계층(Flash Translation Layer, FTL)**: SSD 컨트롤러가 호스트 논리 주소(LBA)를 낸드 플래시의 물리 위치로 변환하고 수명·공간을 관리하는 펌웨어·제어 계층.
- **비제자리 갱신(Out-of-Place Update)**: 낸드 플래시의 덮어쓰기 불가 특성으로 인해 기존 위치를 지우지 않고 새로운 빈 페이지에 기록 후 기존 페이지를 무효화하는 기법.
- **쓰기 전 소거(Erase-before-Write)**: 낸드 플래시는 페이지 단위로 읽기·프로그램하고 블록 단위로 소거하는 특성. 실제 단위 크기는 제품과 세대에 따라 다르다.

</details>

- 정의/개념: 호스트 논리 주소를 낸드 물리 위치로 사상하면서 공간 회수와 수명 분산까지 떠맡는 **플래시 변환 계층(Flash Translation Layer, FTL)**
- 배경/필요성: 낸드는 **쓰기 전 소거** 제약 때문에 덮어쓰기를 지원하지 못해, 호스트가 기대하는 블록 장치 의미론을 그대로 제공할 수 없음

#### 한줄 요약
- FTL은 성능을 위한 계층이 아니라 낸드가 블록 장치인 척하도록 만드는 번역 계층이며, SSD의 예측 불가능한 지연은 전부 이 위장의 대가다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가비지 컬렉션(Garbage Collection, GC)**: 무효 페이지가 누적된 희생 블록(Victim Block)에서 유효 페이지를 새 블록으로 복사 후 희생 블록 전체를 소거하여 빈 공간을 확보하는 작업.
- **마모도 평준화(Wear Leveling)**: 낸드 블록의 P/E Cycle(소거 수명) 편차를 줄이기 위해 모든 블록이 균등하게 소거되도록 분산하는 수명 관리 알고리즘.
- **쓰기 증폭 계수(Write Amplification Factor, WAF)**: 호스트 쓰기량 대비 실제 낸드에 기록된 데이터량의 비율. GC·메타데이터·정렬 방식이 WAF를 높이며, 압축·중복 제거 같은 기능을 제외한 일반적 정의에서는 1 이상으로 본다.

</details>

- **비제자리 갱신**으로 새 빈 페이지에 기록 후 기존 페이지 무효화
- **가비지 컬렉션(Garbage Collection, GC)**으로 희생 블록을 소거해 가용 저장 공간 확보
- **마모도 평준화**와 WAF 제어로 블록 수명 편차·내부 쓰기량 감소

#### 한줄 요약
- **비제자리 갱신**은 쓰기를 빠르게 만드는 대신 뒷정리를 미루는 방식이라, **쓰기 증폭 계수(Write Amplification Factor, WAF)**라는 형태로 빚이 쌓였다가 나중에 청구된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **L2P 매핑 테이블(Logical-to-Physical Mapping Table)**: 호스트 LBA 번지를 낸드 플래시 다이/채널/블록/페이지 번호(PBA)로 변환하는 핵심 룩업 테이블.
- **PLP(Power-Loss Protection)**: 예기치 못한 정전 시 보조 탄탈륨 커패시터 전력으로 컨트롤러 DRAM 캐시 데이터를 낸드에 안전하게 플러시하는 회로.

</details>

```text
[SSD 컨트롤러]
├─ 호스트 인터페이스 (NVMe·PCIe)
├─ FTL 펌웨어
│  ├─ L2P 매핑 엔진
│  ├─ 가비지 컬렉터
│  ├─ 마모도 평준화기
│  └─ 배드 블록 관리기
├─ 온보드 DRAM·SRAM (L2P 테이블·쓰기 버퍼)
├─ 낸드 플래시 제어기 (다중 채널·다중 다이)
└─ PLP 회로
```

선의 의미: 가지(`├─`)는 소유 관계이며, FTL 펌웨어만이 호스트 주소 체계와 낸드 물리 체계 양쪽에 걸쳐 있음

| 구성요소 | 책임 |
|:---|:---|
| **L2P 매핑 테이블** 엔진 | 호스트 LBA와 낸드 PBA 간 매핑 관리 |
| 가비지 컬렉터 | 낭비된 희생 블록 선택, 유효 페이지 이주 및 물리적 소거 수행 |
| 마모도 평준화기 | 낸드 블록 전체의 소거 횟수 편차 분산 |
| 배드 블록 관리기 | 결함 블록 검출과 예비 블록으로의 대체 |
| **PLP(Power-Loss Protection)** | 정전 시 캐시 데이터와 매핑 메타데이터 플러시 |

#### 한줄 요약
- 매핑 테이블이 휘발성 DRAM에 있다는 사실이 구조 전체의 약점이며, SSD 신뢰성 논의가 항상 정전 보호로 귀결되는 이유도 여기에 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Victim Block(희생 블록)**: 가비지 컬렉션 대상으로 선정된 낸드 블록. 무효 페이지 비율 외에도 마모도·온도·지연 목표가 선택 기준에 반영될 수 있다.

</details>

```text
호스트 LBA 쓰기 요청 도달
        │
  빈 페이지에 기록 → L2P 갱신 → 이전 페이지 무효화
        │
   여유 클린 블록이 임계치 이상인가?
   ┌────┴─────┐
  예           아니오
   │             │
쓰기 완료 응답   희생 블록 선정 (무효율·마모도·온도)
   │             │
   │        유효 페이지를 클린 블록으로 복사
   │             │
   │        희생 블록 전체 소거
   └────┬────────┘
        │
   여유 공간 확보 후 응답
```

분기 결과: 여유가 있으면 쓰기가 페이지 기록 한 번으로 끝나지만, 임계치를 밑돌면 유효 페이지 복사와 블록 소거가 쓰기 경로 안에서 동기적으로 일어나 지연이 자릿수 단위로 튐

#### 한줄 요약
- **Victim Block(희생 블록)** 선정이 무효율만 보지 않고 마모도까지 함께 따진다는 점에서, GC는 공간 회수 작업이면서 동시에 수명 관리 작업이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **매핑 단위(Mapping Granularity)**: 주소를 페이지 단위로 사상할지 블록 단위로 사상할지 정하는 기준으로, Page-Level은 세밀한 임의 쓰기 처리를 돕지만 매핑 저장 공간이 크고, Block-Level은 매핑 공간을 줄이는 대신 임의 갱신 비용이 커질 수 있으며, Hybrid는 두 특성을 절충한다.

</details>

| **매핑 단위** | 페이지 매핑 (Page-Level) | 블록 매핑 (Block-Level) | 하이브리드 매핑 (Hybrid/Log) |
|:---|:---|:---|:---|
| 적용 기준 | 임의 쓰기 성능이 중요하고 매핑 메모리 확보 가능 | 순차 쓰기 중심이며 매핑 메모리 최소화 필요 | 매핑 메모리와 임의 쓰기 성능 절충 |
| 핵심 특징 | 페이지 단위 주소 매핑으로 임의 쓰기 처리 유연성 확보 | 블록 단위 매핑으로 매핑 테이블 저장 공간 절감 | 데이터 블록과 로그 블록을 조합해 절충 |
| 한계 | 대용량 매핑 테이블 저장·캐시 자원 필요 | 임의 갱신에서 복사·병합 비용 증가 가능 | 로그 블록 관리·병합·GC 복잡도 증가 |

#### 한줄 요약
- 세 방식의 차이는 매핑 테이블을 담을 DRAM을 얼마나 살 수 있느냐로 환원되므로, 매핑 정책 선택은 알고리즘 문제가 아니라 원가 문제다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Over-Provisioning(OP)**: 일부 낸드 용량을 호스트에 노출하지 않고 GC·마모도 관리의 여유 공간으로 남겨 WAF와 지연을 완화하는 기법.
- **TRIM (Deallocate)**: OS가 더 이상 필요하지 않은 LBA 범위를 SSD에 알려 GC가 해당 데이터를 유효 데이터로 복사하지 않도록 돕는 명령.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 빈 블록 부족으로 전경 GC가 발생해 꼬리 지연 증가 | **OP** 확보·**TRIM** 연동 | 전경 GC 빈도·유효 페이지 복사량 감소 |
| 소규모 임의 쓰기로 **WAF** 증가 | 쓰기 버퍼 집계·페이지 매핑 적용 | 낸드 기록량·소거 수명 소모 감소 |
| 차가운 데이터가 블록을 점유해 마모 편차 증가 | **마모도 평준화**의 정적 모드로 데이터 재배치 | 블록별 소거 횟수 편차 완화 |
| 불시 정전 시 임시 메모리 상의 매핑 테이블 유실 | 전원 차단 보호와 영구 매핑 저널·복구 절차 적용 | 설계된 보호 범위에서 메타데이터·진행 중 쓰기 손상 위험 감소 |

#### 한줄 요약
- **Over-Provisioning(OP)**과 **TRIM (Deallocate)**은 모두 GC가 옮겨야 할 유효 페이지를 줄이는 대책이며, 결국 SSD 성능 관리는 얼마나 안 옮기느냐의 문제로 수렴한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **ZNS(Zoned Namespaces)**: 호스트가 존 단위의 순차 쓰기 규칙을 지켜 데이터 배치와 회수를 협력하도록 하는 NVMe 기능. FTL 관리 부담과 WAF를 줄일 수 있지만 완전히 제거하지는 않는다.

</details>

- 임의 쓰기 SSD는 페이지·하이브리드 매핑과 OP·TRIM으로 **쓰기 증폭 계수(Write Amplification Factor, WAF)**를 관리하고, 순차 배치를 제어할 수 있는 워크로드는 **ZNS**로 FTL의 배치·GC 부담을 추가 완화

#### 한줄 요약
- **ZNS(Zoned Namespaces)**는 호스트가 배치 규칙을 지키는 대가로 FTL 부담을 덜어 주는 거래이며, 성능 이득이 응용 코드 수정 비용을 넘을 때만 성립한다.
