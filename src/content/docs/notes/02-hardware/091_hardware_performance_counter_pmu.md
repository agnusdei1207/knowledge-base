## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PMU(Performance Monitoring Unit)**: CPU 실리콘 다이 내부에 탑재되어 명령어 실행, 캐시 미스, 분기 예측 등 하드웨어 이벤트를 수집하는 전용 모니터링 모듈.
- **PMC(Performance Monitoring Counter)**: PMU 내부에서 특정 하드웨어 이벤트 발생 횟수를 클록 단위로 누적 기록하는 모델별 특수 목적 레지스터(MSR).

</details>

- 정의/개념: CPU 내부의 명령어 실행 수, 캐시 미스, 파이프라인 스톨 등 하드웨어 이벤트를 실시간 계측하는 **성능 모니터링 유닛(PMU)**
- 배경/필요성: 단순 실행 시간 측정만으로는 **파이프라인 스톨 및 메모리 계층 병목 원인의 정량적 규명 불가**

#### 한줄 요약
- CPU 내부 하드웨어 이벤트를 나노초 단위로 계측하여 마이크로아키텍처 병목을 정확히 규명한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IPC(Instructions Per Cycle)**: CPU가 1클록 사이클당 완료(Retire)한 명령어 수로 파이프라인 효율을 나타내는 핵심 성능 지표.
- **PEBS(Precise Event-Based Sampling)**: 이벤트 발생 시 정확한 IP(명령어 포인터)와 레지스터 상태를 하드웨어 버퍼에 덤프하는 정밀 샘플링 기술.

</details>

- 소스 코드 수정 없이 하드웨어 레벨에서 1% 미만 극소 오버헤드로 계측하는 **비침습적 모니터링**
- 사이클당 명령어 처리 수(**IPC**) 및 Topdown 마이크로아키텍처 분석(TMA) 지표 도출
- **PEBS/SPE** 하드웨어 버퍼링을 통한 정확한 핫스팟 코드 라인(IP) 역추적

#### 한줄 요약
- 비침습적 하드웨어 계측을 통해 IPC 저하 원인을 프런트엔드, 백엔드, 메모리 바운드로 정밀 분류한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이벤트 선택기(Event Selector MSR)**: 계측 대상 하드웨어 이벤트 번호, 유저/커널 모드 마스크 및 카운터 활성화를 설정하는 제어 레지스터.

</details>

```text
[CPU 하드웨어 PMU 아키텍처]
|-- 마이크로아키텍처 이벤트 원천 (ALU 연산기·L1/L2/L3 캐시·분기예측 BPU)
|-- PMU 하드웨어 엔진 (Performance Monitoring Unit)
|   |-- 이벤트 선택 레지스터 (Event Selector MSR - IA32_PERFEVTSELx)
|   |-- 성능 카운터 레지스터 (PMC MSR - IA32_PMCx 카운터 어레이)
|   `-- PEBS / SPE 정밀 샘플링 버퍼
`-- OS 커널 및 분석 툴 (Linux perf / Intel VTune / eBPF 프로파일러)
```

선의 의미: 계층 및 하드웨어 계수 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| 마이크로아키텍처 이벤트 | 실행 완료 명령어, 캐시 미스, 파이프라인 플러시 등 펄스 신호 발생 |
| **이벤트 선택 레지스터** | 계측할 이벤트 코드(Mask) 및 사용자/커널(Ring 0/3) 필터링 설정 |
| **성능 카운터(PMC)** | 지정된 이벤트 발생 시 64비트 정수로 하드웨어 카운트 누적 계수 |
| PEBS 버퍼 | 카운터 오버플로우 시 인터럽트 지연 없이 정확한 명령어 포인터(IP) 기록 |
| 분석 도구(perf) | PMI 인터럽트를 수신하고 시분할 다중화 스케일링 보정 후 병목 리포팅 |

#### 한줄 요약
- 이벤트 원천, MSR 선택기, PMC 카운터, PEBS 버퍼, 분석 도구가 결합된 구조다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PMI(Performance Monitor Interrupt)**: 성능 카운터 레지스터가 오버플로우될 때 발생하여 OS 커널의 프로파일링 핸들러를 호출하는 하드웨어 인터럽트.

</details>

```text
분석 대상 이벤트 선정 및 Event Selector MSR 구성
        │
   목표 워크로드 실행 → PMU가 하드웨어 사이클/이벤트 카운팅
        │
   카운터 오버플로우 도달 시 PMI 인터럽트 발생 및 PEBS 덤프
        │
   커널 perf 드라이버가 샘플 수집 및 다중화(Multiplexing) 스케일링 보정
        │
   IPC, 캐시 미스율, TMA 메트릭 산출 → 병목 핫스팟 코드 라인 확정
```

#### 한줄 요약
- MSR 설정 → 하드웨어 계수 → 오버플로우 PMI 발생 → PEBS 덤프 및 다중화 보정 → 병목 분석 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TMA(Topdown Microarchitecture Analysis)**: CPU 파이프라인 슬롯을 Retiring, Bad Speculation, Frontend Bound, Backend Bound 4대 영역으로 계층 분석하는 방법론.

</details>

| 성능 분석 기법 | 하드웨어 PMU 계측 (PMC) | 소프트웨어 프로파일링 | 커널 eBPF 트레이싱 | 시뮬레이션 (gem5) |
|:---|:---|:---|:---|:---|
| 분석 계층 | CPU 마이크로아키텍처 | 애플리케이션 함수/라인 | 커널 시스템 콜/네트워크 | 가상 사이클 단위 모델 |
| 오버헤드 | **1% 미만 (극소 간섭)** | 5~30% (프로브 왜곡) | 1~3% (JIT 안전 계측) | $10^3\sim 10^5\times$ (극도로 느림) |
| 장점 | 캐시 미스, 파이프라인 스톨 정량화 | 콜 스택 및 함수 실행시간 | 커널-유저 공간 통합 추적 | 미출시 하드웨어 구조 검증 |

#### 한줄 요약
- 심층 하드웨어 병목 규명에는 PMU가, 시스템 콜 추적에는 eBPF가, 함수 분석에는 소프트웨어 프로파일링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카운터 다중화(Counter Multiplexing)**: 물리 카운터 수(보통 4~8개)보다 많은 이벤트를 측정하기 위해 시간을 쪼개어 번갈아 활성화한 후 비례 스케일링하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 물리 카운터 부족으로 다수 이벤트 동시 측정 불가 | **시분할 카운터 다중화** 및 시간 가중치 스케일링 | 수십 개 이벤트를 단일 프로파일링 세션에서 동시 추정 |
| 코어 마이그레이션으로 인한 카운터 데이터 왜곡 | CPU Affinity(코어 피닝) 적용으로 분석 프로세스 고정 | 코어 이동에 따른 캐시 미스 오차 제거 및 일관성 확보 |
| 과도한 샘플링으로 인한 PMI 인터럽트 폭주 | **PEBS 하드웨어 버퍼링** 및 적응형 샘플링 주기 조정 | 프로파일링 인터럽트 부하 90% 절감 및 시스템 안정화 |
| 가상화 VM 내부에서 하드웨어 카운터 접근 불가 | 하이퍼바이저 vPMU(가상 PMU) 패스스루 활성화 | 클라우드 게스트 VM 내 마이크로아키텍처 프로파일링 실현 |

#### 한줄 요약
- 카운터 다중화, 코어 피닝, PEBS 버퍼링, vPMU 활성화로 실무 계측 정확도를 확보한다.

## Ⅶ. 결론

- 고성능 시스템 최적화는 **하드웨어 PMU 및 Intel TMA 방법론**을 적용하고, **Linux perf/eBPF 연계**를 통해 캐시 미스 및 파이프라인 스톨 원천 해소

#### 한줄 요약
- 하드웨어 성능 카운터는 블랙박스 상태의 CPU 내부 파이프라인 동작을 정량화하여 근본적 성능 병목을 해결하는 핵심 도구다.
