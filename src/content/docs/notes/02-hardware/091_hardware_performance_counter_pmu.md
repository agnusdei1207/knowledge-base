## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **하드웨어 성능 카운터**: 프로세서 내부에서 발생한 성능 사건을 하드웨어 레지스터로 계수하는 기능이다.
- **중앙 처리 장치(Central Processing Unit, CPU)**: 명령 실행과 시스템 자원 제어를 담당하는 처리 장치이다.
- **성능 감시 장치(Performance Monitoring Unit, PMU)**: 측정할 하드웨어 이벤트를 선택하고 카운터•오버플로를 제어하는 처리기 내부 장치이다.

</details>

- 정의/개념: CPU 내부의 명령 실행과 캐시•분기•정체 사건을 하드웨어 카운터로 선택•계수하여 병목 가설을 검증하는 성능 계측 체계이다.
- 배경/필요성: 총 실행 시간만으로는 지연이 연산 부족, 캐시 미스, 분기 실패 또는 실행 자원 정체 중 어디에서 발생했는지 구분할 수 없다.

#### 한줄 요약

- **CPU 내부 사건 계수**로 실행•메모리 병목 원인을 분석한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **사이클당 명령 수(Instructions per Cycle, IPC)**: 클록 사이클당 완료한 명령어 수로 파이프라인 처리 효율을 나타내는 지표이다.
- **캐시 미스율**: 전체 캐시 접근 중 원하는 데이터가 없어 하위 메모리 계층을 조회한 비율이다.
- **카운터 다중화**: 제한된 물리 카운터를 여러 이벤트가 시간 분할하여 공유하는 방식이다.

</details>

![PMU 다중화 실행 비율에 따른 보정 배율 차트](/study/diagrams/pmu-multiplex-scale.svg)

> **실행 비율 10%**에서 다중화 보정 배율 10배 증가

- **하드웨어 계수•샘플링**으로 낮은 간섭의 총량•위치를 제공한다.
- **IPC•캐시 미스율**로 실행•메모리 병목 판별이 핵심이다.
- **카운터 다중화**는 환산 오차 발생이 핵심이다.

$$
\mathrm{IPC}=\frac{N_{\mathrm{retired}}}{N_{\mathrm{cycles}}},\qquad
\mathrm{MissRate}=\frac{N_{\mathrm{miss}}}{N_{\mathrm{access}}},\qquad
\hat N=N_{\mathrm{raw}}\frac{T_{\mathrm{enabled}}}{T_{\mathrm{running}}}
$$

- **\(N_{\mathrm{retired}}\)**: 은퇴 명령 수이다.
- **\(N_{\mathrm{cycles}}\)**: 클록 사이클 수이다.
- **\(N_{\mathrm{miss}}\)**: 캐시 미스 수이다.
- **\(N_{\mathrm{access}}\)**: 전체 캐시 접근 수이다.
- **\(\hat N,N_{\mathrm{raw}}\)**: 보정 추정치•원시 계수이다.
- **\(T_{\mathrm{enabled}}\)**: 측정 요청 시간이다.
- **\(T_{\mathrm{running}}\)**: 실제 계수 시간이다.
- 같은 구간•코어와 일정한 **사건 발생률**을 가정한 다중화를 추정한다.

#### 한줄 요약

- **저간섭 하드웨어 계수**와 CPU 모델별 이벤트 의미 차이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **이벤트 원천(Event Source)**: 사이클•명령 은퇴•캐시 미스 같은 CPU 사건을 생성하는 구성이다.
- **이벤트 선택기(Event Selector)**: 원시 이벤트 코드와 권한 조건으로 계수 대상을 고르는 구성이다.
- **성능 카운터(Performance Counter)**: 선택 사건을 누적하고 임계값에서 오버플로를 발생시키는 구성이다.
- **수집•분석 도구(Collection•Analysis Tool)**: 계수•샘플을 보정하고 성능 지표와 병목을 분석하는 구성이다.

</details>

```text
PMU 계측 구조
├─ 이벤트 원천
├─ 이벤트 선택기
├─ 성능 카운터
└─ 수집•분석 도구
```

가지의 의미: PMU 계측 구조가 사건 생성•선택•계수와 분석 책임으로 구성되는 정적 포함 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 이벤트 원천 | **CPU 사건 생성** |
| 이벤트 선택기 | **사건•권한 선택** |
| 성능 카운터 | **사건 누적•오버플로** |
| 수집•분석 도구 | **비율 보정•병목 분석** |

#### 한줄 요약

- **사건 생성•선택•계수•분석**의 PMU 계측 구조이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **샘플링**: 카운터 오버플로 시점의 실행 위치와 문맥을 기록하여 병목 위치를 추정하는 방식이다.
- **명령어 은퇴**: 명령 실행 결과가 확정되어 프로그램 상태에 반영된 상태이다.

</details>

```text
[CPU 병목 가설]
       │
       ▼
1. 이벤트•측정 조건 선택
       │
       ▼
2. 동일 워크로드 반복 실행
       │
       ▼
3. 사건 계수•위치 샘플 수집
       │
       ▼
4. 활성 시간 보정•지표 산출
       │
       ▼
5. 코드 위치•사건 상관 분석
       │
       ▼
[병목 가설 채택•기각]
```

**동작 원리**

1. **이벤트•측정 조건 선택**: 대상 CPU 모델이 제공하는 이벤트 가운데 병목 가설을 검증할 사건과 계산식을 정한다.
2. **동일 워크로드 반복 실행**: 코어 배치와 입력 데이터 및 전력 상태를 고정하여 비교 가능한 실행을 반복한다.
3. **사건 계수•위치 샘플 수집**: 카운터 총량과 오버플로 시점의 명령 주소•호출 문맥을 함께 기록한다.
4. **활성 시간 보정•지표 산출**: 카운터 다중화로 실제 측정한 시간을 보정하고 IPC와 캐시 미스율 같은 비율을 계산한다.
5. **코드 위치•사건 상관 분석**: 사건이 집중된 코드와 다른 관련 지표를 교차 확인하여 병목 가설이 반복 실행에서도 일관적인지 검증한다.

#### 한줄 요약

- 같은 부하에서 **사건 총량과 발생 코드 위치**를 결합하여 CPU 병목 가설을 검증한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **소프트웨어 프로파일링**: 실행 위치•호출 경로•시간을 수집하여 지연이 집중된 코드를 찾는 분석 방식이다.
- **계측 오버헤드**: 측정 코드와 샘플링이 원래 프로그램의 시간•자원 사용에 추가하는 비용이다.

</details>

| 분석 방식 | PMU 계측 | 소프트웨어 프로파일링 |
|:---|:---|:---|
| 적용 기준 | **CPU 내부 병목**가설 검증 | **지연 코드 위치•호출 관계** 탐색 |
| 핵심 특징 | CPU 사건을 **하드웨어로 계수** | 코드 위치•호출 경로 **샘플링** |
| 한계 | **카운터 수•모델별 이벤트** 차이 | **계측•샘플링 오버헤드** |

> 요약: 코드 위치는 **프로파일링**, CPU 병목은 **PMU**을 검증한다.

#### 한줄 요약

- 소프트웨어 프로파일링은 느린 코드 위치를 찾고, PMU는 그 위치에서 발생한 **CPU 내부 사건의 원인**을 분석한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **활성 시간(Enabled Time)**: 이벤트 측정이 요청된 전체 시간이다.
- **실행 시간(Running Time)**: 이벤트가 실제 물리 카운터에 배치되어 계수된 시간이다.
- **코어 고정**: 측정 스레드를 같은 CPU 코어에서 계속 실행하도록 묶는 조치이다.
- **메모리 정체**: 필요한 데이터가 메모리 계층에서 도착하기를 기다려 명령 실행이 멈춘 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CPU 세대별 **이벤트 의미•단위 차이** | 공식 정의와 **원시 이벤트 코드** 기록 | **측정 해석 오류** 방지 |
| 물리 카운터 부족으로 **다중화 오차** 발생 | 핵심 사건 축소와 **활성 시간 보정•반복 측정** | **계수 신뢰도** 향상 |
| 스레드 이동•주파수 변화로 **비교 왜곡** | **코어 고정•부하•전원 정책 통제** | **재현 가능한 비교** |
| 높은 샘플링 빈도로 **실행 간섭** 발생 | 오버헤드 측정 후 **표본 주기 조절** | 관측 정확도를 유지하며 **계측 부하** 감소 |

#### 한줄 요약

- 반복 부하의 **캐시 미스율•IPC**로 메모리 정체를 검증한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **이벤트 활성 시간**: 다중화 중 특정 이벤트가 실제 물리 카운터에 연결되어 계수된 시간이다.
- **분기 예측 실패**: 예측한 명령 경로와 실제 분기 결과가 달라 파이프라인을 다시 채워야 하는 사건이다.

</details>

- 코드 위치는 **프로파일링**, CPU 병목 원인은 **PMU**을 검증한다.

#### 한줄 요약

- 프로파일링으로 코드 위치를 좁힌 뒤 **서로 관련된 여러 PMU 사건**을 반복 측정하여 병목 원인을 교차 검증한다.
