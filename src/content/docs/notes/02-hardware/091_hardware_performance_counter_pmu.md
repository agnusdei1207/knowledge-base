## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 모니터링 유닛(Performance Monitoring Unit, PMU)**: CPU 실리콘 다이 내부에 물리적으로 내장되어 명령어 실행 완료, 캐시 미스, 분기 예측 실패, 파이프라인 스톨 등 하드웨어 마이크로아키텍처 이벤트를 실시간 수집하는 전용 회로 모듈.
- **성능 모니터링 카운터(Performance Monitoring Counter, PMC)**: PMU 내부에서 특정 하드웨어 이벤트의 발생 횟수를 클록 사이클 단위로 누적 기록하는 64비트 특수 목적 레지스터(MSR).

</details>

- 정의/개념: CPU 코어 내부 이벤트를 초저오버헤드로 실시간 계측하는 **하드웨어 PMU** 아키텍처
- 배경/필요성: 소프트웨어 프로파일링의 오버헤드 및 왜곡으로 인한 **파이프라인 세부 병목 규명** 한계 극복

#### 한줄 요약
- CPU 내부 하드웨어 이벤트를 나노초 단위로 계측하여 마이크로아키텍처 병목을 정확히 규명한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: CPU 코어가 1클록 사이클 동안 최종 완료(Retire)시킨 평균 명령어 수로, 마이크로아키텍처 파이프라인 효율의 절대 지표.
- **정밀 이벤트 기반 샘플링(Precise Event-Based Sampling, PEBS)**: 이벤트 오버플로우 발생 시 인터럽트 지연 없이 정확한 명령어 포인터(IP)와 레지스터 상태를 하드웨어 버퍼에 덤프하는 기술.

</details>

- 비침습적 초저오버헤드: 코드 수정 없이 **하드웨어 레벨**에서 **1% 미만 오버헤드**로 계측
- **IPC** 및 TMA 메트릭 산출: 클록당 명령어 처리 수 및 **Topdown 분석(TMA)** 병목 지표 정량화
- 하드웨어 덤프 정밀 추적: **PEBS** 버퍼를 통해 지연 왜곡 없는 **정확한 명령어 주소(IP)** 역추적

#### 한줄 요약
- 비침습적 하드웨어 계측을 통해 IPC 저하 원인을 프런트엔드, 백엔드, 메모리 바운드로 정밀 분류한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이벤트 선택 레지스터(Event Selector MSR)**: 계측 대상 하드웨어 이벤트 번호, 유닛 마스크(UMask), 유저/커널(Ring 0/3) 필터링 및 카운터 활성화를 설정하는 MSR.
- **성능 모니터 인터럽트(Performance Monitor Interrupt, PMI)**: PMC 카운터가 오버플로우(Overflow)될 때 발생하여 OS 프로파일링 드라이버를 호출하는 하드웨어 인터럽트.

</details>

```text
[CPU 하드웨어 PMU 및 프로파일링 아키텍처]
 ├── 마이크로아키텍처 이벤트 원천 ─── ALU 연산기 / L1·L2·L3 캐시 / 분기예측기(BPU) / ROB
 ├── CPU 내장 PMU 하드웨어 엔진
 │   ├── 이벤트 선택 레지스터 (PerfEvtSel) ── 이벤트 코드 + Ring 0/3 필터링 구성
 │   ├── 성능 모니터링 카운터 (PMC) ──────── 64비트 정수 하드웨어 이벤트 누적 계수
 │   ├── PEBS / SPE 정밀 샘플링 버퍼 ─────── 카운터 오버플로우 시 레지스터 상태 자동 덤프
 │   └── PMI 인터럽트 발생기 ──────────────── 오버플로우 시 커널로 NMI/PMI 신호 송출
 └── OS 커널 및 분석 도구 ──────────── Linux perf 드라이버 / Intel VTune / eBPF
```

선의 의미: 가지(`├──`, `└──`)는 하드웨어 소속 및 계수 파이프라인; 파이프라인 이벤트가 PMC 카운터에 누적되다 오버플로우되면 PEBS 버퍼와 PMI를 통해 OS 프로파일러로 전달됨

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| 이벤트 발생 원천 | 코어 파이프라인 | 실행 완료, 캐시 미스, 분기 오예측 시 전기 펄스 신호 생성 | **하드웨어 이벤트** |
| 이벤트 선택 MSR | PMU 제어단 | 계측할 이벤트 코드 및 **Ring 0/3 필터링** 설정 | PerfEvtSel MSR |
| 성능 카운터 (PMC) | PMU 데이터단 | 지정된 이벤트 발생 시 **64비트 레지스터**에 즉시 누적 계수 | IA32_PMCx 어레이 |
| PEBS 샘플링 버퍼 | PMU 버퍼단 | 오버플로우 시 왜곡 없이 **명령어 포인터(IP)** 자동 덤프 | **정밀 프로파일링** |
| OS 프로파일러 | 커널/사용자단 | PMI 인터럽트 수신 및 시분할 다중화 보정 후 **TMA 병목 리포팅** | Linux perf, VTune |

#### 한줄 요약
- PMU 시스템은 이벤트 원천, 이벤트 선택 MSR, PMC 카운터, PEBS 버퍼 및 OS 프로파일러로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상위-하위 마이크로아키텍처 분석(Topdown Microarchitecture Analysis, TMA)**: 파이프라인 슬롯을 Retiring, Bad Speculation, Frontend Bound, Backend Bound 4대 영역으로 계층 분석하는 방법론.

</details>

```text
[프로파일링 대상 애플리케이션 실행]
                │
                ▼
1. PerfEvtSel MSR 이벤트 코드 및 계측 조건 설정
                │
                ▼
2. PMU 하드웨어 엔진의 실시간 이벤트 계수 수행
                │
                ▼
3. PMC 성능 카운터 임계치 도달 및 오버플로우 발생
                │
                ▼
4. PEBS 버퍼 내 현재 명령어 포인터(IP) 및 레지스터 자동 덤프
                │
                ▼
5. PMI 인터럽트 발생 및 OS perf 드라이버 TMA 병목 분석
                │
                ▼
[마이크로아키텍처 병목 분석 결과 도출]
```

분기 결과: 하드웨어 카운터와 TMA 분석을 통해 **캐시 미스 및 파이프라인 스톨** 지점을 데이터 기반으로 규명함

#### 한줄 요약
- MSR 설정 ➔ 하드웨어 계수 ➔ 오버플로우 발생 ➔ PEBS 자동 덤프 ➔ PMI 인터럽트 및 TMA 분석 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **카운터 다중화(Counter Multiplexing)**: 코어당 물리 카운터 수(4~8개)보다 많은 이벤트를 계측하기 위해 시간을 쪼개어 번갈아 활성화한 후 비례 보정하는 기법.

</details>

| 성능 계측 및 분석 기법 | 하드웨어 PMU 계측 (PMC / PEBS) | 소프트웨어 프로파일링 (gprof) | 커널 eBPF 트레이싱 | 풀 시스템 시뮬레이터 (gem5) |
|:---|:---|:---|:---|:---|
| 계측 대상 계층 | **CPU 마이크로아키텍처** | 애플리케이션 함수/소스 라인 | 커널 시스템 콜, 네트워크 | 가상 하드웨어 모델 |
| 시스템 측정 오버헤드 | **1% 미만 (극소 간섭)** | 5 ~ 30% (프로브 왜곡 심각) | **1 ~ 3% (JIT 안전 계측)** | $10^3 \sim 10^5\times$ (극도로 느림) |
| 계측 신뢰성 및 정밀도 | **사이클 단위 이벤트 정확** | 샘플링 간격 및 OS 왜곡 | 커널-유저 공간 통합 추적 | 완벽한 제어 및 가시성 |
| 주요 적용 분야 | **캐시 미스, 파이프라인 스톨** | 단순 함수별 실행 시간 분석 | 커널 병목 및 분산 추적 | 미출시 하드웨어 검증 |

#### 한줄 요약
- 심층 하드웨어 병목 규명에는 PMU가, 시스템 콜 추적에는 eBPF가, 함수 분석에는 소프트웨어 프로파일링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가상 PMU(vPMU)**: 하이퍼바이저가 게스트 가상 머신(VM)에 물리 CPU의 성능 카운터 레지스터를 가상화하여 노출하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 물리 카운터 부족으로 다수 이벤트 불가 | **시분할 카운터 다중화** 및 비례 스케일링 보정 | 수십 개 이벤트를 **단일 세션에서 동시 추정** |
| 스레드 코어 이동으로 인한 데이터 왜곡 | **CPU Affinity(taskset)** 기반 분석 프로세스 코어 고정 | 캐시 오차 제거 및 **계측 일관성 확보** |
| 클라우드 가상 머신 내 카운터 접근 불가 | 하이퍼바이저 **vPMU(가상 PMU)** 패스스루 활성화 | 게스트 VM 내 **마이크로아키텍처 프로파일링** |

#### 한줄 요약
- 실무에서는 카운터 다중화로 많은 이벤트를 재고, 코어 피닝으로 오차를 없애며, vPMU로 클라우드 가상화를 지원한다.

## Ⅶ. 결론

- 병목 분석 정밀도와 가상화 요구에 따라 **PMU**와 **PEBS**를 통합 적용

#### 한줄 요약
- 하드웨어 성능 카운터는 블랙박스 상태의 CPU 내부 파이프라인 동작을 정량화하여 근본적 성능 병목을 해결하는 핵심 도구다.
