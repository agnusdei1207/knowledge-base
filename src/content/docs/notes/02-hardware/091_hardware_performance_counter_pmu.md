## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **성능 모니터링 유닛(Performance Monitoring Unit, PMU)**: CPU 실리콘 다이 내부에 물리적으로 내장되어 명령어 실행 완료, 캐시 미스, 분기 예측 실패, 파이프라인 스톨 등 하드웨어 마이크로아키텍처 이벤트를 실시간 수집하는 전용 회로 모듈.
- **성능 모니터링 카운터(Performance Monitoring Counter, PMC)**: PMU 내부에서 특정 하드웨어 이벤트의 발생 횟수를 클록 사이클 단위로 누적 기록하는 64비트 특수 목적 레지스터(MSR).

</details>

- 정의/개념: CPU 코어 내부의 사이클, 실행 완료 명령어(Retire), 캐시 미스, 파이프라인 스톨 등 하드웨어 이벤트를 1% 미만 극소 오버헤드로 실시간 계측하는 **하드웨어 PMU(Performance Monitoring Unit) 아키텍처**
- 배경/필요성: 단순 소프트웨어 실행 시간(Wall-clock Time) 측정만으로는 **파이프라인 프런트엔드/백엔드 스톨, 분기 예측 실패 및 캐시 계층 병목 원인의 정량적 규명 불가**

#### 한줄 요약
- CPU 내부 하드웨어 이벤트를 나노초 단위로 계측하여 마이크로아키텍처 병목을 정확히 규명한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: CPU 코어가 1클록 사이클 동안 최종 완료(Retire)시킨 평균 명령어 수로, 마이크로아키텍처 파이프라인 효율의 절대 지표.
- **정밀 이벤트 기반 샘플링(Precise Event-Based Sampling, PEBS)**: 이벤트 오버플로우 발생 시 인터럽트 지연 없이 정확한 명령어 포인터(IP)와 레지스터 상태를 하드웨어 버퍼에 덤프하는 기술.

</details>

- 비침습적 초저오버헤드: 코드 수정이나 프로브 삽입 없이 **하드웨어 레벨에서 1% 미만의 극소 오버헤드로 계측**
- **IPC(Instructions Per Cycle)** 및 TMA 메트릭 산출: 클록당 명령어 처리 수와 인텔 Topdown 마이크로아키텍처 분석(TMA) 4대 병목 지표 정량화
- 하드웨어 덤프 기반 정밀 추적: **PEBS / ARM SPE(Statistical Profiling Extension)** 버퍼를 통해 지연 왜곡(Skid) 없는 정확한 핫스팟 코드 라인(IP) 역추적

#### 한줄 요약
- 비침습적 하드웨어 계측을 통해 IPC 저하 원인을 프런트엔드, 백엔드, 메모리 바운드로 정밀 분류한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **이벤트 선택 레지스터(Event Selector MSR)**: 계측 대상 하드웨어 이벤트 번호, 유닛 마스크(UMask), 유저/커널(Ring 0/3) 필터링 및 카운터 활성화를 설정하는 MSR.
- **성능 모니터 인터럽트(Performance Monitor Interrupt, PMI)**: PMC 카운터가 오버플로우(Overflow)될 때 발생하여 OS 프로파일링 드라이버를 호출하는 하드웨어 인터럽트.

</details>

```text
[CPU 하드웨어 PMU 및 프로파일링 아키텍처]
 ┌─ [1. 마이크로아키텍처 이벤트 원천] ── ALU 연산기 / L1·L2·L3 캐시 / 분기예측기(BPU) / ROB
 │                                                    │ (이벤트 펄스 신호 발생)
 ├─ [2. CPU 내장 PMU 하드웨어 엔진] ─────────────────┴──────────────────────────────────────┐
 │   ├─ [이벤트 선택 레지스터 (PerfEvtSel MSR)] ── 이벤트 코드 + Ring 0/3 필터링 구성       │
 │   ├─ [성능 모니터링 카운터 (PMC MSR 어레이)] ── 64비트 정수 하드웨어 이벤트 누적 계수     │
 │   ├─ [PEBS / SPE 정밀 샘플링 버퍼] ────────── 카운터 오버플로우 시 레지스터 상태 자동 덤프│
 │   └─ PMI 인터럽트 발생기 ───────────────────── 오버플로우 시 커널로 NMI/PMI 신호 송출    │
 └──────────────────────┬───────────────────────────────────────────────────────────────────┘
                        │ (PMI 인터럽트 신호)
 ┌──────────────────────▼───────────────────────────────────────────────────────────────────┐
 │ [3. OS 커널 및 분석 도구] ── Linux perf 드라이버 / Intel VTune / eBPF (TMA 병목 리포팅)   │
 └──────────────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 가지(`├─`, `└─`)는 하드웨어 소속 및 계수 파이프라인; 파이프라인 이벤트가 PMC 카운터에 누적되다 오버플로우되면 PEBS 버퍼와 PMI를 통해 OS 프로파일러로 전달됨

| 구성요소 | 계층 및 위치 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|:---|
| **이벤트 발생 원천** | 코어 파이프라인 | 실행 완료 명령어, 캐시 미스, 분기 오예측 발생 시 전기 펄스 신호 생성 | 하드웨어 이벤트 |
| **이벤트 선택 MSR** | PMU 제어단 | 계측할 이벤트 코드, UMask 및 사용자/커널(Ring 0/3) 필터링 설정 | PerfEvtSel MSR |
| **성능 카운터 (PMC)** | PMU 데이터단 | 지정된 이벤트 발생 시 64비트 하드웨어 레지스터에 즉시 누적 계수 | IA32_PMCx 어레이 |
| **PEBS 샘플링 버퍼** | PMU 버퍼단 | 카운터 오버플로우 시 지연 왜곡 없이 **정확한 명령어 포인터(IP) 하드웨어 덤프** | 정밀 프로파일링 |
| **OS 프로파일러(perf)**| 커널/사용자단 | PMI 인터럽트를 수신하고 시분할 다중화 스케일링 보정 후 **TMA 병목 리포팅** | Linux perf, VTune |

#### 한줄 요약
- PMU 시스템은 이벤트 원천, 이벤트 선택 MSR, PMC 카운터, PEBS 버퍼 및 OS 프로파일러로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상위-하위 마이크로아키텍처 분석(Topdown Microarchitecture Analysis, TMA)**: 파이프라인 슬롯을 Retiring, Bad Speculation, Frontend Bound, Backend Bound 4대 영역으로 계층 분석하는 방법론.

</details>

```text
1. 분석 대상 이벤트(CPU 사이클, 캐시 미스, 분기 실패) 선정 및 PerfEvtSel MSR 설정
                      │
                      ▼
2. 대상 애플리케이션 워크로드 실행 ➔ PMU 하드웨어가 실시간으로 이벤트 계수
                      │
                      ▼
3. PMC 성능 카운터가 샘플링 주기 임계치에 도달하여 오버플로우(Overflow) 발생
                      │
                      ▼
4. 하드웨어 PEBS 버퍼에 현재 명령어 주소(IP) 및 CPU 레지스터 상태 자동 기록
                      │
                      ▼
5. PMI(Performance Monitor Interrupt) 발생 ➔ OS 커널 perf 드라이버 핸들러 호출
                      │
                      ▼
6. 샘플 데이터 수집 및 시분할 다중화(Multiplexing) 시간 가중치 보정
                      │
                      ▼
7. TMA 4대 메트릭(Retiring, Frontend, Backend, Bad Speculation) 및 핫스팟 코드 라인 확정
```

분기 결과: **하드웨어 카운터와 TMA 분석을 통해** 단순 추측이 아닌 데이터 기반으로 정확한 병목(캐시 미스 vs 분기 실패) 지점을 찾아냄

#### 한줄 요약
- MSR 설정 ➔ 하드웨어 계수 ➔ 오버플로우 PMI 발생 ➔ PEBS 덤프 및 다중화 보정 ➔ TMA 병목 분석 순으로 진행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **카운터 다중화(Counter Multiplexing)**: 코어당 물리 카운터 수(4~8개)보다 많은 이벤트를 계측하기 위해 시간을 쪼개어 번갈아 활성화한 후 비례 보정하는 기법.

</details>

| 성능 계측 및 분석 기법 | 하드웨어 PMU 계측 (PMC / PEBS) | 소프트웨어 프로파일링 (gprof) | 커널 eBPF 트레이싱 | 풀 시스템 시뮬레이터 (gem5) |
|:---|:---|:---|:---|:---|
| 계측 대상 계층 | **CPU 마이크로아키텍처 파이프라인** | 애플리케이션 함수/소스 라인 | 커널 시스템 콜, 네트워크 스택 | 사이클 단위 가상 하드웨어 모델 |
| 시스템 측정 오버헤드 | **1% 미만 (극소 간섭)** | 5 ~ 30% (프로브 왜곡 심각) | **1 ~ 3% (JIT 기반 안전 계측)** | $10^3 \sim 10^5\times$ (극도로 느림) |
| 계측 신뢰성 및 정밀도 | **클록 사이클 및 하드웨어 이벤트 정확**| 샘플링 간격 및 OS 스케줄링 왜곡 | 커널-유저 공간 통합 추적 우수 | 완벽한 제어 및 가시성 제공 |
| 주요 적용 분야 | **캐시 미스, 파이프라인 스톨 정량화** | 단순 함수별 실행 시간 프로파일링 | 커널 병목 및 분산 분산 추적 | 미출시 신규 하드웨어 아키텍처 검증 |

#### 한줄 요약
- 심층 하드웨어 병목 규명에는 PMU가, 시스템 콜 추적에는 eBPF가, 함수 분석에는 소프트웨어 프로파일링이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **가상 PMU(vPMU)**: 하이퍼바이저가 게스트 가상 머신(VM)에 물리 CPU의 성능 카운터 레지스터를 가상화하여 노출하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 물리 카운터(4~8개) 부족으로 수십 개 이벤트 동시 계측 불가 | **시분할 카운터 다중화(Multiplexing) 및 비례 스케일링 보정** | 수십 개 하드웨어 이벤트를 단일 세션에서 동시 추정 |
| 스레드 코어 마이그레이션으로 인한 카운터 데이터 왜곡 | **taskset / CPU Affinity 기반 분석 대상 프로세스 코어 고정** | 코어 이동에 따른 L1/L2 캐시 오차 제거 및 일관성 확보 |
| 클라우드 가상 머신(VM) 내부에서 하드웨어 카운터 접근 불가 | **하이퍼바이저 vPMU(가상 PMU) 패스스루 기능 활성화** | 클라우드 게스트 VM 내 마이크로아키텍처 프로파일링 실현 |

#### 한줄 요약
- 실무에서는 카운터 다중화로 많은 이벤트를 재고, 코어 피닝으로 오차를 없애며, vPMU로 클라우드 가상화를 지원한다.

## Ⅶ. 결론

- 고성능 미션 크리티컬 시스템의 마이크로아키텍처 병목을 정밀 규명하기 위해 **CPU 내장 PMU 및 Intel TMA 4단계 분석 방법론을 표준 적용**하고, 측정 오차를 극소화하기 위해 **PEBS 정밀 샘플링 및 CPU Affinity 코어 고정**을 연계하며, 클라우드 환경에서는 **vPMU 가상화 패스스루**를 활성화하는 체계적인 하드웨어 성능 엔지니어링 확립

#### 한줄 요약
- 하드웨어 성능 카운터는 블랙박스 상태의 CPU 내부 파이프라인 동작을 정량화하여 근본적 성능 병목을 해결하는 핵심 도구다.
