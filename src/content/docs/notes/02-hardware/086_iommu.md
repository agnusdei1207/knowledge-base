## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: 랜카드나 그래픽카드가 메모리에 함부로 빨대 꽂지 못하게 멱살 잡고 주소 검사를 하는 치명적인 하드웨어 경비원이다.
- **입출력 가상 주소(Input/Output Virtual Address, IOVA)**: 멍청한 외부 장비들이 진짜 물리 메모리 주소인 줄 알고 착각하며 부르는 가짜 껍데기 주소이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 느려 터진 CPU를 거치지 않고 장비가 다이렉트로 메모리를 쑤시고 파먹는 초고속 깡패 기술이다.

</details>

- 정의: 랜카드나 그래픽카드(I/O 디바이스)가 부르는 **입출력 가상 주소(IOVA)**를 진짜 물리 주소로 번역해 주고, 아무 데나 쑤시지 못하게 멱살 잡고 통제하는 **입출력 메모리 관리 장치(IOMMU)** 하드웨어
- 배경: 멍청한 기계 장치들이 권한도 없이 **직접 메모리 접근(DMA)**을 갈겨서 시스템 커널이나 남의 가상 머신(VM) 영역을 박살 내는 끔찍한 사태를 원천 차단하기 위함

#### 한줄 요약

- 외부 장비가 CPU 몰래 메모리에 빨대를 꽂을 때, 진짜 주소로 번역해 주고 권한을 통제하는 문지기 칩이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **입출력 변환 색인 버퍼(Input/Output Translation Lookaside Buffer, IOTLB)**: 방금 주소 번역한 거 까먹지 않게 잽싸게 적어둬서, 다음번엔 0.001초 만에 하이패스로 통과시켜 주는 초고속 메모리 수첩이다.
- **아이오엠엠유 도메인(IOMMU Domain)**: "가상 머신 1번은 1구역, 2번은 2구역!" 하고 장치마다 절대 못 넘어오게 철조망을 쳐버리는 보안 격리 구역이다.
- **단일 루트 입출력 가상화(Single Root I/O Virtualization, SR-IOV)**: 물리 랜카드 한 장을 가짜 랜카드 수십 장으로 갈기갈기 찢어서 가상 머신들에 하나씩 꽂아주는 분신술 마법이다.

</details>

- 장치나 VM별로 "넌 여기까지만 써라" 하고 메모리 구역을 칼같이 찢어버리는 **아이오엠엠유 도메인** 격리를 강제함.
- 연속적인 **입출력 가상 주소(IOVA)**를 실제로는 비연속적인 쪼가리 물리 페이지에 매핑해서 메모리 파편화를 씹어먹음.
- 단일 장치를 수십 개로 찢어주는 **에스알 아이오브이(SR-IOV)**랑 엮어서, 가상 머신마다 랜카드를 다이렉트로 꽂아주는 패스스루(Passthrough)를 완성함.

#### 한줄 요약

- 장치마다 구역(도메인)을 나눠 가두고, 가짜 주소를 진짜로 번역하며, 가상 머신에 랜카드를 다이렉트로 꽂아준다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **입출력 페이지 테이블(I/O Page Table)**: "가짜 1번은 진짜 100번에 있고, 여긴 쓰기 금지야!" 하고 꼼꼼하게 적어둔 절대 규칙 장부이다.
- **장치 컨텍스트 테이블(Device Context Table)**: 장비의 주민번호(BDF)를 보고 얘가 어느 구역(도메인) 소속인지 빠르게 찾아내는 색인표이다.

</details>

```text
[ 입출력 메모리 방화벽 십자포화 프레임워크 ]
[ 도메인 관리자 (총책임자) ] ── [ 입출력 페이지 테이블 (절대 장부) ]
                                          │
                                          ▼
   [ DMA 장치 (무식한 노가다꾼) ] ── [ IOMMU•IOTLB (톨게이트 검문소) ]
                                          │
                                          ▼
                            [ 호스트 물리 메모리 (진짜 데이터) ]
```

| 구성요소 | 책임 |
|:---|:---|
| 도메인 관리자 | "이 VM은 저 그래픽카드 써" 하고 짝을 지어주고(**도메인** 할당), 주소 변환표를 세팅하는 총책임자 |
| **입출력 페이지 테이블** | 가짜 주소(IOVA)를 진짜 주소(HPA)로 번역하고, "여긴 읽기만 해라" 하고 권한까지 쾅쾅 박아둔 번역 장부 |
| IOMMU•**IOTLB** | 번역표(장부)를 미친 듯이 뒤져서 주소를 바꾸고, 방금 찾은 건 **IOTLB** 캐시에 짱박아두는 톨게이트 |
| DMA 장치 | 뇌 비우고 그냥 IOVA 주소 들이밀면서 "데이터 내놔!" 하고 **DMA** 요청을 날려대는 무식한 노가다 장비 |

#### 한줄 요약

- 장비가 가짜 주소를 부르면 톨게이트(IOMMU)가 장부를 뒤져 진짜 주소로 바꿔주고 접근을 막거나 허락한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **아이오엠엠유 폴트(IOMMU Fault)**: 권한 없는 장비가 남의 메모리를 쑤시려고 할 때 뿜어내는 "접근 금지 삐용삐용!" 비상 사이렌이다.

</details>

```text
[ 입출력 다이렉트 억세스 검문소 십자포화 흐름 ]
                                 │
                                 ▼
         [ 1. 신원 확인: 장비가 BDF 이름표 들이밀면 소속 도메인 확인 ]
                                 │
                                 ▼
      [ 2. 캐시 뒤지기: 수첩(IOTLB)에 있는 주소면 하이패스, 없으면 장부로 감 ]
                                 │
                                 ▼
      [ 3. 장부 빡검문: 수첩에 없으면 페이지 테이블(장부) 바닥까지 싹 다 뒤짐 ]
                                 │
                                 ▼
    [ 4. 멱살 검증: 진짜 주소 맞는지, 쓰기 금지 구역 쑤시려는 건 아닌지 칼검사 ]
                                 │
                 ┌───────────────┴───────────────┐
             ( 통과 허락 )                   ( 선 넘었을 때 )
                 ▼                               ▼
       [ 물리 메모리 직행 (DMA) ]        [ 5. IOMMU 폴트 뿜고 철퇴 차단 ]
```

### 동작 원리

1. 신원 확인(도메인 선택): 장치가 이름표(BDF)를 들이밀면 IOMMU가 "너 어느 구역 소속이냐?" 하고 확인을 갈김.
2. 캐시 뒤지기: 전에 허락받은 주소인지 **IOTLB**를 뒤져보고, 있으면 하이패스로 통과시킴.
3. 장부 빡검문: 캐시에 없으면 **입출력 페이지 테이블**을 바닥까지 싹 다 뒤져서 매핑표를 찾아냄.
4. 멱살 검증: 주소가 맞는지, 쓰기 금지 구역인데 쓰려고 한 건 아닌지 얄짤없이 검사함.
5. 철퇴 차단: 권한 없거나 엉뚱한 주소면 **아이오엠엠유 폴트(IOMMU Fault)** 에러를 뿜고 통신을 강제로 끊어버림.

#### 한줄 요약

- 신원 확인 후 캐시를 뒤지고, 없으면 장부를 까봐서 권한을 확인한 뒤에야 메모리 진입을 허가한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패스스루(Passthrough)**: 하이퍼바이저 껍데기를 다 찢어버리고, 가상 머신에 랜카드나 그래픽카드를 물리적으로 다이렉트 직결시키는 속도 몰빵 마법이다.

</details>

| 비교 항목 | **아이오엠엠유 활성화** (VT-d Enabled) | **아이오엠엠유 비활성화** (Bypass Mode) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 서버에 가상 머신 수십 개 띄워놓고 각각 랜카드나 그래픽카드를 직접 꽂아줘야(**패스스루**) 할 시 | 그냥 깡통 PC에서 운영체제 하나만 띄워놓고 그래픽카드 극한의 속도(0 지연)로 풀파워 돌릴 시 |
| 아키텍처 핵심 구현 특징 | 가짜 주소를 진짜 주소로 변환해 주고, 아무나 메모리 못 찌르게 철통 보안(**도메인** 격리)을 치는 문지기 모드 | IOMMU 끄고 장치가 하드웨어 물리 주소를 다이렉트로 때려 박게 내버려 두는 무법지대 모드 |
| 극복해야 할 태생적 한계점 | 주소 번역표 못 찾으면(**IOTLB Miss**) 딜레이가 튀고 성능이 미세하게 깎여나감 | 장치가 미쳐 날뛰어서 커널 메모리를 쑤셔버려도 막을 방법이 없는 보안 재앙 그 자체 |

#### 한줄 요약

- 보안과 가상 머신 할당이 필요하면 IOMMU를 켜고, 1%의 속도 깎임도 용납 못 하면 끈다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **입출력 변환 색인 버퍼 무효화(IOTLB Invalidation)**: "야, 옛날 주소 다 지워!" 하고 쓸모없어진 캐시 기록을 빗자루로 쓸어버리는 청소 명령어이다.
- **인텔 입출력 가상화 기술(Intel VT-d)**: 인텔이 칩에 때려 박아놓은 IOMMU 하드웨어 기술로, 가상 머신 굴릴 때 밥줄 같은 방어벽이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 캐시 못 찾고 장부 뒤지는 짓(**IOTLB Miss**)을 너무 자주 해서 10기가 랜카드 속도가 반토막 나는 끔찍한 병목 터짐 | 찌끄레기 페이지 대신 거대한 통짜 페이지(Huge Pages)로 묶어서 번역표 덩치를 줄여버림 | 캐시 폭발을 씹어먹고 메모리 번역 딜레이를 극한까지 깎아내려 무지막지한 전송량 사수 |
| 메모리 다 쓰고 반납했는데 캐시(**IOTLB**)에 옛날 주소가 남아있어서, 엉뚱한 장치가 남의 새 메모리를 쑤셔버리는 재앙 | 매핑 끊을 때마다 "이 주소 캐시 싹 다 지워라!" 하고 **입출력 변환 색인 버퍼 무효화** 명령어를 얄짤없이 날림 | 잔여 캐시 때문에 생기는 치명적인 보안 펑크와 데이터 오염을 100% 원천 차단 |
| 해킹당한 싸구려 랜카드가 DMA를 갈겨서 윈도우 커널을 통째로 파괴하려는 무차별 묻지마 공격 시전 | 아예 기본 설정을 '전부 차단'으로 걸고, 딱 필요한 버퍼만 찔끔 열어주는 짠돌이 최소 권한 매핑 시전 | 악성 I/O 장치가 시스템을 엎어버리는 끔찍한 제로데이 붕괴 사태를 완벽하게 틀어막음 |

#### 한줄 요약

- 통짜 페이지(Huge Pages)로 딜레이를 잡고, 캐시는 바로바로 지우며, 최소 권한만 열어줘서 방어해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **IOMMU 채택 기준(IOMMU Adoption Criteria)**: 가상 머신에 물리 장비를 꽂을 건지, 랜카드가 뇌를 비우고 커널을 박살 낼 위험이 있는지 따져보고 문지기를 세울지 말지 결정하는 기준표이다.

</details>

- **IOMMU 채택 기준** 원칙에 따라, 가상 머신 물리 직결 및 비신뢰 장비 DMA는 **IOMMU 활성화**, 로컬 단일 호스트 초고속 I/O는 **비활성화(항등 매핑)** 채택 기조 확립함

#### 한줄 요약

- 가상 머신에 장비 꽂아줄 땐 닥치고 IOMMU 켜고, 깡통 PC에서 게임할 땐 그냥 꺼라.
