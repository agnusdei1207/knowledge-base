## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IOMMU(Input-Output Memory Management Unit)**: PCI/PCIe 입출력 장치의 DMA 요청 시 I/O 가상 주소(IOVA)를 호스트 물리 주소(HPA)로 변환하고 메모리 접근 권한을 제어하는 하드웨어 모듈(Intel VT-d, AMD-Vi, ARM SMMU).
- **IOVA(Input/Output Virtual Address)**: 디바이스 드라이버와 장치 DMA 컨트롤러가 사용하는 가상 I/O 메모리 주소 체계.

</details>

- 정의/개념: 장치의 직접 메모리 접근 요청에서 **IOVA(Input/Output Virtual Address)** 활용 물리 주소로 변환하고 접근 범위를 제한하는 **IOMMU(Input-Output Memory Management Unit)**
- 배경/필요성: 직접 메모리 접근은 CPU의 페이지 권한 검사를 통째로 건너뛰므로, 장치 하나가 시스템 메모리 전체를 읽고 쓸 수 있음

#### 한줄 요약
- CPU에만 메모리 보호를 걸어 두면 장치가 그 옆으로 지나가므로, 보호 경계는 연산 주체가 아니라 메모리에 접근하는 모든 주체에 걸려야 한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IOTLB(Input/Output Translation Lookaside Buffer)**: IOMMU 내부에서 최근 변환된 IOVA $\to$ HPA 주소 매핑 엔트리를 캐싱하여 페이지 테이블 탐색 오버헤드를 줄이는 고속 캐시.
- **도메인 격리(IOMMU Domain Isolation)**: 장치 집합마다 독립 I/O 페이지 테이블과 권한을 적용해 DMA 가능 범위를 제한하는 기법.

</details>

- 장치별로 독립된 주소 공간을 부여하는 **도메인 격리(IOMMU Domain Isolation)**
- 흩어진 물리 페이지를 장치에는 하나의 연속 버퍼처럼 보이게 매핑
- 가상 머신에 물리 장치를 직결하면서도 접근 범위를 그 VM으로 한정

#### 한줄 요약
- 이 장치가 없으면 장치 직결은 성능 기법이 아니라 보안 사고이므로, 가상화에서 패스스루의 전제 조건은 속도가 아니라 격리다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **장치 컨텍스트 테이블(Device Context Table)**: PCIe 장치의 BDF(Bus:Device:Function) 번호를 인덱스로 하여 해당 장치가 속한 IOMMU 도메인의 페이지 테이블 루트 포인터를 찾는 테이블.
- **I/O 페이지 테이블(I/O Page Table)**: IOVA와 물리 메모리 주소(HPA) 간의 매핑 정보와 읽기/쓰기(R/W) 권한 플래그를 담은 다단계 테이블.

</details>

```text
[IOMMU 주소 변환 경로]
├─ PCIe 장치 (식별자와 가상 주소로 DMA 요청)
├─ IOMMU 엔진
│  ├─ 장치 컨텍스트 테이블 (식별자 → 도메인 페이지 테이블)
│  ├─ IOTLB 캐시 (최근 변환 결과 보관)
│  ├─ I/O 페이지 테이블 워커 (캐시 미스 시 순회)
│  └─ 권한 검증·오류 통지
└─ 호스트 물리 메모리
```

선의 의미: 가지(`├─`)는 소유 관계이며, 장치와 메모리 사이에 IOMMU가 끼어 있어 우회 경로가 존재하지 않음

| 구성요소 | 책임 |
|:---|:---|
| PCIe 장치 | 고유 식별자를 붙여 DMA 요청 전송 |
| **장치 컨텍스트 테이블(Device Context Table)** | 장치 식별자로 소속 도메인의 페이지 테이블 탐색 |
| **IOTLB(Input/Output Translation Lookaside Buffer)** | 최근 변환 결과를 캐싱해 순회 비용 절감 |
| **I/O 페이지 테이블(I/O Page Table)** 워커 | 캐시 미스 시 다단계 테이블 순회로 주소 도출 |
| 권한 검증·오류 통지 | 권한 위반 시 전송을 차단하고 예외를 알림 |

#### 한줄 요약
- 구조가 CPU 쪽 메모리 관리 장치와 거의 같은 이유는 문제가 같기 때문이며, 다른 점은 이 경계를 넘는 주체가 신뢰할 수 없는 외부 장치라는 사실 하나다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **IOMMU Fault**: 매핑되지 않은 주소 접근, 쓰기 금지 영역 쓰기 시도, 권한 없는 BDF 요청 시 트랜잭션을 강제 차단하고 시스템 로그를 남기는 하드웨어 예외.

</details>

```text
장치가 식별자와 가상 주소로 DMA 요청
        │
   식별자로 소속 도메인과 페이지 테이블 선택
        │
   변환 결과가 캐시에 있는가?
   ┌────┴─────┐
  예           아니오
   │             │
   │        다단계 페이지 테이블 순회
   └────┬────────┘
        │
   요청 유형이 페이지 권한과 맞는가?
   ┌────┴─────┐
  예           아니오
   │             │
물리 주소로     전송 차단 후
DMA 전달        예외 통지
```

분기 결과: 캐시 적중 여부는 성능만 좌우하지만 권한 검증 결과는 허용과 차단을 가르므로, 두 갈림길은 이름만 비슷할 뿐 성격이 완전히 다름

#### 한줄 요약
- **IOMMU Fault** 발생했다는 것은 드라이버가 잘못 매핑했거나 장치가 규약을 벗어났다는 뜻이므로, 이 예외는 성능 지표가 아니라 결함 신호로 다뤄야 한다.

## Ⅴ. 종류 및 비교

| IOMMU 동작 모드 | IOMMU 활성화 (Strict Mode) | IOMMU 우회 (Bypass Mode) | 소프트웨어 바운스 버퍼 | 에뮬레이션 가상 I/O |
|:---|:---|:---|:---|:---|
| 적용 기준 | 가상화 클라우드 및 고보안 제로 트러스트 | 베어메탈 HPC 초저지연 연산 | 32비트 레거시 구형 하드웨어 | 단순 범용 하이퍼바이저 가상화 |
| 핵심 특징 | IOVA 변환·권한 검증과 장치 도메인 격리 | 주소 변환 없이 물리 주소 직접 사용 | 접근 가능한 메모리로 임시 복사 | 하이퍼바이저가 가상 장치 동작 중개 |
| 한계 | IOTLB 미스·무효화와 페이지 워크 비용 | 장치 오류·공격의 DMA 범위 제한 곤란 | CPU 복사와 버퍼 관리 비용 | VM-Exit·에뮬레이션 비용 증가 |

#### 한줄 요약
- 네 모드는 격리 강도와 지연을 맞바꾼 눈금이며, 우회를 선택하는 순간 장치를 신뢰한다는 가정이 시스템 보안의 전제로 들어온다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IOTLB Invalidation**: DMA 버퍼 해제(Unmap) 시 IOTLB 캐시에 남아 있는 잔여 주소 엔트리를 강제로 플러시하여 Use-After-Free DMA 보안 취약점을 막는 명령.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잦은 캐시 미스로 전송 처리량 저하 | 지원 범위에서 대용량 페이지와 일괄 매핑 적용 | 캐시 도달 범위 확대와 순회 횟수 감소 |
| 버퍼 해제 후 잔여 매핑으로 반납 메모리 접근 | 매핑 해제 즉시 **IOTLB Invalidation** 수행 | 반납된 메모리에 대한 접근 경로 제거 |
| 외부 포트에 꽂은 장치가 메모리를 탈취 | 부팅 전과 잠금 상태를 포함한 보호 활성화와 포트 정책 | 비인가 장치의 접근 가능 범위 제한 |
| 장치 직결 시 인터럽트가 다른 VM에 간섭 | 인터럽트 리매핑 테이블 적용 | VM별 독립 인터럽트 라우팅 보장 |

#### 한줄 요약
- 매핑을 만드는 일보다 지우는 일이 위험을 좌우하므로, 이 장치의 보안은 하드웨어 성능이 아니라 드라이버가 해제 시점을 지키느냐에 달려 있다.

## Ⅶ. 결론

- 장치 직결과 가상 기능 분할은 도메인 격리와 인터럽트 리매핑을 전제로만 허용하고, 격리 이득이 없는 단일 목적 장치에 한해 우회를 검토하되 성능 차이를 실측하고 감수할 위협 범위를 명시

#### 한줄 요약
- 하드웨어는 허용된 범위만 지킬 뿐 그 범위를 누가 정했는지는 묻지 않으므로, 실제 보호 수준은 매핑을 만드는 소프트웨어의 정확성을 넘지 못한다.
