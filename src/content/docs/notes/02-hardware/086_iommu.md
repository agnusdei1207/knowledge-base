## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **입출력 가상 주소(Input/Output Virtual Address, IOVA)**: 장치가 DMA 요청에 사용하는 가상 주소이다.
- **직접 메모리 접근(Direct Memory Access, DMA)**: 장치가 처리기를 거치지 않고 메모리를 읽고 쓰는 방식이다.
- **입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)**: IOVA를 물리 주소로 변환하고 DMA 권한을 검사하는 하드웨어이다.
- **가상 머신(Virtual Machine, VM)**: 격리된 가상 하드웨어에서 게스트 운영체제를 실행하는 시스템이다.

</details>

- 정의/개념: **IOMMU**는 장치의 **IOVA**를 호스트 물리 주소로 변환하고 페이지별 **DMA** 접근 권한을 검사하는 메모리 관리 장치이다.
- 배경/필요성: 장치가 물리 주소로 직접 DMA를 수행하면 잘못되거나 악의적인 요청이 다른 프로세스•VM의 메모리를 침범하여 데이터를 훼손할 수 있다.

#### 한줄 요약

- **IOMMU**는 **IOVA** 변환과 **DMA** 권한 검사를 함께 수행한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **IOMMU 도메인**: 변환표와 접근 권한을 공유하는 장치 격리 단위이다.
- **입출력 변환 색인 버퍼(Input/Output Translation Lookaside Buffer, IOTLB)**: 최근 IOVA 변환 결과를 저장하는 캐시이다.
- **단일 루트 입출력 가상화(Single Root I/O Virtualization, SR-IOV)**: 하나의 PCIe 장치를 여러 가상 기능으로 나눠 VM에 직접 할당하는 기술이다.

</details>

- **IOMMU 도메인**과 **SR-IOV**로 장치•VM별 직접 할당 DMA 범위를 분리한다.
- IOVA→물리 주소 변환과 페이지 권한을 동시에 검사한다.
- **IOTLB** 미스와 무효화는 장치 주소 변환 지연을 늘린다.

#### 한줄 요약

- **IOMMU 도메인** 격리와 **IOTLB** 미스•무효화 비용이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **도메인 관리자(Domain Manager)**: 장치별 주소 매핑과 DMA 권한 및 수명주기를 관리하는 구성이다.
- **페이지 테이블(Page Table)**: IOVA와 물리 주소 대응 및 접근 권한을 기록하는 구성이다.
- **IOMMU•IOTLB**: 주소 변환과 권한 검증 및 최근 변환 캐시를 제공하는 구성이다.
- **DMA 장치(DMA Device)**: IOVA와 장치 식별자로 메모리 접근을 요청하는 구성이다.

</details>

```text
[도메인 관리자] -- [페이지 테이블] -- [IOMMU•IOTLB] -- [DMA 장치]
```

선의 의미: 도메인 관리자가 페이지 테이블의 주소•권한을 관리하고 IOMMU•IOTLB가 이를 참조해 DMA 장치 접근을 중재하는 정적 의존 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 도메인 관리자 | 매핑•권한 관리 |
| 페이지 테이블 | 주소•권한 저장 |
| IOMMU•IOTLB | 변환•접근 검증 |
| DMA 장치 | 메모리 접근 요청 |

#### 한줄 요약

- **도메인 관리자**, **페이지 테이블**, **IOMMU•IOTLB**가 DMA 접근 경계를 구성한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **페이지 테이블 순회**: IOTLB 미스 때 변환표 계층을 따라 물리 주소와 권한을 찾는 동작이다.
- **IOMMU 폴트**: 무효 주소나 허용 범위 밖의 DMA 요청을 차단하면서 발생하는 예외이다.
- **IOMMU 도메인 선택**: 장치 식별자로 적용할 변환표와 권한 집합을 고르는 단계이다.
- **IOTLB 변환 조회**: IOVA의 최근 변환과 권한이 캐시에 있는지 확인하는 단계이다.
- **주소·권한 검증**: DMA 길이와 매핑 및 읽기·쓰기 권한을 검사하는 단계이다.
- **허용 또는 폴트 처리**: 검증된 요청만 전달하고 비인가 요청을 차단하는 단계이다.

</details>

```text
[DMA 장치의 IOVA•식별자]
             │
             ▼
1. IOMMU 도메인 선택
             │
             ▼
2. IOTLB 변환 조회
       ┌─────┴─────────┐
       │ 적중          │ 미스
       │               ▼
       │       3. 페이지 테이블 순회
       │               │
       └───────┬───────┘
               ▼
4. 주소•권한 검증
       ┌───────┴────────┐
       │ 허용           │ 위반
       ▼                ▼
[물리 DMA 접근]   5. IOMMU 폴트•차단
       │
       ▼
   [DMA 완료]
```

### 동작 원리

1. **IOMMU 도메인 선택**: 요청자 장치 식별자로 적용할 주소 변환표와 접근 권한 집합을 선택한다.
2. **IOTLB 변환 조회**: I/O 가상 주소에 대응하는 최근 변환과 권한이 캐시에 있는지 확인한다.
3. **페이지 테이블 순회**: IOTLB가 빗나가면 메모리의 I/O 페이지 테이블에서 물리 주소와 권한을 읽어 캐시한다.
4. **주소•권한 검증**: DMA 요청의 전체 길이가 유효한 매핑 안에 있고 읽기•쓰기 권한을 만족하는지 검사한다.
5. **허용 또는 폴트 처리**: 검증된 요청만 메모리로 전달하고 무효•비인가 요청은 차단한 뒤 IOMMU 폴트를 기록한다.

#### 한줄 요약

- IOMMU는 **IOMMU 도메인 선택**, **IOTLB 변환 조회**, **주소·권한 검증**을 모두 통과한 DMA 요청만 메모리로 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **장치 직접 할당**: 물리 장치나 가상 기능을 특정 VM이 하이퍼바이저 중재 없이 사용하게 하는 방식이다.
- **권한 기반 DMA 격리**: 장치마다 허용된 메모리 범위만 접근하도록 IOMMU가 요청을 검사하는 방식이다.
- **최소 권한 매핑**: 전송에 필요한 시점과 버퍼 범위만 DMA에 허용하는 정책이다.

</details>

| DMA 격리 방식 | IOMMU 사용 | IOMMU 미사용 |
|:---|:---|:---|
| 적용 기준 | **장치 직접 할당**•외부 확장 포트 | 신뢰된 단일 목적 장치 |
| 핵심 특징 | IOVA 변환•**권한 기반 DMA 격리** | 장치 주소의 물리 메모리 직접 접근 |
| 한계 | IOTLB 미스•매핑 무효화 지연 | 임의 메모리 침범•데이터 훼손 |

> 요약: 직접 DMA 장치에는 IOMMU로 허용 버퍼만 공개한다.

#### 한줄 요약

- 외부 장치와 VM 직접 할당 장치에는 필요한 버퍼만 노출하는 **최소 권한 매핑**을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **IOTLB 무효화**: 매핑 변경 뒤 캐시에 남은 낡은 주소 변환을 제거하는 동작이다.
- **큰 페이지**: IOTLB 항목 하나가 더 넓은 메모리 영역을 덮게 하는 큰 주소 단위이다.
- **드라이버 버퍼**: 장치와 운영체제 드라이버가 DMA로 데이터를 교환하도록 할당한 메모리 영역이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장치에 과도한 DMA 범위를 열어 메모리 노출 확대 | 전송 시점•버퍼 단위 **최소 권한 매핑** | DMA 접근 범위 축소 |
| 작은 페이지•분산 **드라이버 버퍼**로 IOTLB 미스 증가 | 연속 버퍼와 **큰 페이지** 적용 | **페이지 테이블 순회** 비용 감소 |
| 매핑 변경 뒤 낡은 IOTLB 항목으로 해제 메모리 접근 | 변경 순서와 **IOTLB 무효화** 완료 동기화 | 재사용 메모리 오염 방지 |
| 같은 장치•도메인에서 **IOMMU 폴트** 반복 | 폴트 주소 기록과 해당 도메인 격리 | 공격•드라이버 결함 식별 |

#### 한줄 요약

- 장치별 **드라이버 버퍼**에 **최소 권한 매핑**을 적용하고 변경•해제할 때 **IOTLB 무효화**를 수행한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **장치 디스크립터**: 장치가 처리할 버퍼 주소•길이•명령을 기록한 메모리 구조이다.
- **DMA 격리 선택 기준**: 장치 신뢰도와 공유 범위 및 직접 할당 여부에 따라 IOMMU 적용 수준을 정하는 기준이다.

</details>

- **DMA 격리 선택 기준**에 따라 외부•VM 장치는 **IOMMU**로 **장치 디스크립터**의 버퍼 범위를 검증하고, 신뢰된 단일 목적 장치도 필요한 범위만 직접 DMA에 공개한다.

#### 한줄 요약

- 장치별 **최소 권한 매핑**과 IOTLB 무효화 빈도를 최적화한다.
