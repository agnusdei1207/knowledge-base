## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라이닝(Pipelining)**: 명령어 처리 과정을 복수의 하위 단계(IF-ID-EX-MEM-WB)로 세분화하고, 서로 다른 명령어를 매 클록 사이클마다 병렬로 중첩 실행하여 시스템의 전체 처리량을 극대화하는 하드웨어 설계 기법.
- **처리량(Throughput)**: 단위 시간당 중앙처리장치가 처리를 완료하여 파이프라인을 빠져나가는 총 명령어 수.
- **지연시간(Latency)**: 단일 명령어가 파이프라인의 첫 단계인 인출부터 마지막 단계인 결과 기록까지 전체 경로를 통과하는 데 소요되는 총 시간.

</details>

- 정의/개념: 명령어 처리 과정을 복수의 독립 하위 단계로 분할하고, 서로 다른 명령어가 매 클록마다 각 단계를 중첩 점유하도록 설계한 **파이프라이닝** 마이크로아키텍처
- 배경/필요성: 단일 사이클 및 비파이프라인 구조에서는 한 명령어 실행 중 나머지 하드웨어 유닛이 유휴(Idle) 상태에 머물러 자원 활용률과 **처리량**이 낮아지므로, 단계 경계에 레지스터를 두어 유닛마다 서로 다른 명령어가 동시에 머물게 해 매 클록 1명령어 완료를 지향

#### 한줄 요약
- 파이프라이닝은 단일 명령어의 **지연시간**을 단축하는 것이 아니라, 여러 명령어를 중첩 실행하여 시스템 전체의 처리량(Throughput)을 극대화하는 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: CPU가 단일 클록 사이클당 평균적으로 완료하는 명령어 수(이상적 단일 파이프라인에서 IPC=1).
- **최장 단계 지연(Critical Path Delay)**: 파이프라인 단계 중 조합 논리 회로의 전파 지연이 가장 긴 단계의 소요 시간으로, 프로세서의 최대 동작 클록 주파수를 결정.
- **파이프라인 스톨(Pipeline Stall)**: 해저드 발생 시 특정 단계의 전진을 멈추고 버블(NOP)을 삽입하여 데이터 정합성을 유지하는 하드웨어 제어 동작.

</details>

- 처리량 극대화: 5단계 중첩 실행을 통해 이상적인 환경에서 **클록당 명령어 수(IPC)**를 1에 근접하도록 향상
- 클록 주기 결정: 분할된 파이프라인 단계 중 **최장 단계 지연**에 의해 전체 프로세서 클록 주파수가 제약되므로 단계별 균등 분할 필수
- 해저드 페널티: 데이터·제어·구조 충돌 발생 시 **파이프라인 스톨** 및 플러시가 수반되어 유효 명령어 완료율 저하

#### 한줄 요약
- 파이프라인 단수를 늘릴수록 클록 주파수는 올라가지만, 해저드 발생 시 치러야 하는 스톨 및 플러시 손실도 함께 증가한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch, IF)**: PC가 가리키는 주소의 명령어를 메모리/캐시에서 읽어와 IF/ID 레지스터에 적재하고 PC를 갱신하는 단계.
- **명령어 해독(Instruction Decode, ID)**: 명령어의 Opcode와 피연산자를 해독하고 레지스터 파일에서 피연산자 값을 인출하는 단계.
- **실행(Execute, EX)**: ALU를 통해 산술·논리 연산 수행, 메모리 유효 주소 계산, 분기 조건 판정을 수행하는 단계.
- **메모리 접근(Memory Access, MEM)**: 데이터 메모리(D-Cache)에 접근하여 로드 데이터를 읽거나 스토어 데이터를 기록하는 단계.
- **결과 기록(Write Back, WB)**: ALU 연산 결과 또는 메모리 로드 데이터를 최종 목적 레지스터 파일에 기록하는 단계.
- **파이프라인 레지스터(Pipeline Register)**: 인접한 단계 경계(IF/ID, ID/EX, EX/MEM, MEM/WB)에 위치하여 데이터와 제어 신호를 매 클록 동기화하는 래치 레지스터.

</details>

```text
[5단계 파이프라인 CPU]
|
+-- [처리 유닛]
|   +-- [명령어 인출·해독 유닛]
|   +-- [ALU]
|   +-- [데이터 메모리]
|   `-- [레지스터 파일]
`-- [파이프라인 레지스터]
    +-- [IF/ID]
    +-- [ID/EX]
    +-- [EX/MEM]
    `-- [MEM/WB]
```

선의 의미: 가지(`+--`, `` `-- ``)는 처리 유닛과 단계 간 상태 보존 요소의 포함 관계를 나타냄

| 구성요소 | 책임 |
|:---|:---|
| **명령어 인출(IF)**·**명령어 해독(ID)** 유닛 | PC 기반 인출과 제어 신호 생성 |
| **실행(EX)** 유닛(ALU) | 산술·논리 연산과 분기 조건 판정 |
| **메모리 접근(MEM)** 데이터 메모리 | 적재·저장을 위한 데이터 접근 수행 |
| **결과 기록(WB)** 레지스터 파일 | 피연산자 읽기와 연산 결과 보존 |
| **파이프라인 레지스터** | 단계 사이 중간 상태 보존 |

#### 한줄 요약
- 5단계 파이프라인은 IF-ID-EX-MEM-WB의 5개 실행 유닛과 그 경계를 분리하는 파이프라인 레지스터로 구성되어 매 사이클 병렬 실행을 유지한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정상 상태(Steady State)**: 파이프라인 5개 단계가 모두 유효한 명령어로 채워져 매 클록마다 WB 단계에서 1개의 명령어가 지속 완결되는 상태.
- **파이프라인 플러시(Pipeline Flush)**: 분기 오예측 또는 인터럽트 발생 시 파이프라인 내부에 이미 진입한 후속 명령어들을 무효화(NOP)하는 제어 동작.

</details>

```text
[새 명령어가 IF 단계 진입]
                      │
                      ▼
[1. 진행 장애 요인 판정]
   ┌──────────────────┼──────────────────┐
[ 장애 없음 ]       [ 데이터/구조 의존성 ]   [ 분기 오예측 확정 ]
   │                  │                  │
   ▼                  ▼                  ▼
정상 전진        스톨(Stall) 발생     플러시(Flush) 발생
(매 클록 전진)   (버블 NOP 삽입)      (무효 명령어 비우기)
   │                  │                  │
   │             의존성 해소 후 재개      올바른 목표 주소 재인출
   └──────────────────┼──────────────────┘
                      │
                      ▼
[WB 단계에서 완료 명령어 배출]
```

분기 결과: **정상 상태**에서는 매 클록 1개 명령어가 완료되나, **파이프라인 스톨**은 파이프라인에 버블을 주입하고, **파이프라인 플러시**는 진입된 다수의 명령어를 일괄 폐기함

#### 한줄 요약
- 파이프라인은 정상 상태에서 매 클록 1명령어를 완료하지만, 해저드 발생 시 스톨이나 플러시 제어를 통해 실행 정합성을 복구한다.

## Ⅴ. 종류 및 비교

| 실행 구조 | 5단계 파이프라인 구조 | 순차 비파이프라인 구조 |
|:---|:---|:---|
| 적용 기준 | 교육용 RISC·단순 파이프라인 코어 | 교육용·단순 순차 제어 코어 |
| 핵심 특징 | 명령어 중첩 실행 및 IPC 향상 | 명령어 단일 순차 실행 |
| 한계 | 해저드 발생 시 스톨 및 플러시 오버헤드, 면적 증가 | 기능 유닛 유휴 및 낮은 처리량(CPI >> 1) |
| 클록 주기 | 최장 단계 지연과 레지스터 오버헤드 기준 | 전체 조합 경로 또는 다중 사이클 제어 기준 |
| 제어 복잡도 | 포워딩, 해저드 감지, 분기 예측 회로 필수 | 단순 시퀀서 및 상태 머신만으로 구현 가능 |

#### 한줄 요약
- 처리량이 중요하면 파이프라인, 단순 제어가 중요하면 순차 구조를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 연산 결과를 레지스터 기록(WB) 전에 ALU 출력에서 후속 명령어의 EX 입력으로 직결하는 하드웨어 우회 경로.
- **분기 예측(Branch Prediction)**: 조건부 분기의 방향과 목표 주소를 사전 추측하여 파이프라인 단절을 방지하는 기술.
- **단계 분할(Stage Splitting)**: 임계 지연이 큰 단계를 하위 단계로 재분할하여 프로세서 클록 주파수를 높이는 설계 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 의존성(RAW)으로 인한 파이프라인 스톨 발생 | **포워딩 회로** 구축 및 컴파일러 스케줄링 | 데이터 대기 사이클 제거 및 IPC 유지 |
| 조건부 분기 판정 지연으로 인한 인출 중단 | **동적 분기 예측기** 및 조기 판정 적용 | 제어 해저드에 의한 플러시 페널티 최소화 |
| 특정 단계(MEM/ALU) 지연으로 인한 클록 주파수 저하 | **단계 분할** 및 균등 밸런싱 | 임계 경로 단축 및 최대 동작 주파수 향상 |
| 과도한 단계 세분화로 플러시·레지스터 비용 증가 | 워크로드별 파이프라인 깊이 조정 | 처리량·전력·분기 페널티 절충 |

#### 한줄 요약
- 파이프라인 실무 설계는 포워딩과 분기 예측을 통해 스톨을 방어하고, 단계 분할과 깊이 최적화를 통해 클록 주파수와 페널티의 균형을 잡는다.

## Ⅶ. 결론

- 현대 프로세서의 기본 실행 패러다임으로 정착되었으며, 최근에는 단순 파이프라인 깊이 확대의 전력·분기 페널티 한계를 극복하기 위해 슈퍼스칼라·비순서 실행(OoO) 및 도메인 특화 가속 구조로 고도화 추세

#### 한줄 요약
- 파이프라이닝은 명령어 중첩을 통해 고성능을 구현하는 핵심 마이크로아키텍처이며, 해저드 제어 회로의 완결성이 실질 처리량을 좌우한다.
