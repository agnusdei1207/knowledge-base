## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라이닝(Pipelining)**: 명령어 처리를 여러 단계로 나누고 서로 다른 명령어의 단계를 클록마다 중첩해 실행하는 기법.
- **처리량(Throughput)**: 단위 시간에 CPU가 완료하는 명령어 수.
- **지연시간(Latency)**: 한 명령어가 IF 진입부터 WB 완료까지 걸리는 시간.

</details>

- 정의/개념: 명령어를 IF·ID·EX·MEM·WB 단계로 나눠 서로 다른 명령어의 단계를 중첩해 **처리량**을 높이는 CPU 실행 구조
- 배경/필요성: 비파이프라인 구조에서 한 명령어 완료 전 기능 유닛이 유휴 상태로 낭비되어 처리량 개선 불가

#### 한줄 요약
- 파이프라이닝은 한 명령어를 빨리 끝내기보다, 여러 명령어가 각자 다른 단계를 동시에 통과하게 해 전체 완료 수를 높인다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 평균 한 클록에 완료하는 명령어의 수; 이상적 5단계 파이프라인에서 IPC=1.
- **최장 단계 지연(Critical Path Delay)**: 파이프라인 단계 중 가장 긴 조합 논리 경로 지연으로 전체 클록 주기를 결정.
- **스톨(Stall)**: 해저드로 인해 파이프라인 한 단계의 진행을 멈추는 제어; 스톨 1사이클마다 IPC 감소.

</details>

- 단계 중첩으로 **IPC**를 1에 가깝게 높여 처리량 향상
- **최장 단계 지연**이 전체 클록 주기를 결정해 단계 균등 분할이 중요
- 해저드 발생 시 **스톨**·플러시로 처리량이 감소해 해저드 완화가 설계 핵심

#### 한줄 요약
- 단계가 고르게 짧고 스톨이 적을수록 파이프라인은 매 클록마다 명령어 하나를 완료에 가까워진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch, IF)**: PC가 가리키는 주소에서 명령어를 메모리로부터 인출하는 파이프라인 첫 단계.
- **명령어 해독(Instruction Decode, ID)**: 연산 코드와 피연산자 필드를 해석해 제어 정보와 레지스터 값을 준비하는 단계.
- **실행(Execute, EX)**: 산술·논리 연산·주소 계산·분기 조건 평가를 수행하는 단계.
- **메모리 접근(Memory Access, MEM)**: 로드·스토어 명령어의 데이터 메모리 읽기·쓰기를 수행하는 단계.
- **결과 기록(Write Back, WB)**: 연산 또는 로드 결과를 목적 레지스터에 기록하는 마지막 단계.
- **파이프라인 레지스터(Pipeline Register)**: IF/ID·ID/EX·EX/MEM·MEM/WB 경계에서 데이터와 제어 정보를 클록 단위로 래치하는 레지스터.

</details>

```text
[5단계 파이프라인]
  IF ── ID ── EX ── MEM ── WB
  │    │    │     │      │
IF/ID ID/EX EX/MEM MEM/WB (파이프라인 레지스터)
```

선의 의미: `──`는 단계 순서 연결; `│` 아래는 단계 경계의 파이프라인 레지스터

| 구성요소 | 책임 |
|:---|:---|
| IF | **PC** 기반 명령어 인출·PC 증가 |
| ID | 명령어 해독·레지스터 피연산자 준비 |
| EX | ALU 연산·주소 계산·분기 조건 평가 |
| MEM | 로드·스토어 데이터 메모리 접근 |
| WB | 연산·로드 결과 레지스터 기록 |
| 파이프라인 레지스터 | 단계별 데이터·**제어 신호** 클록 단위 보관 |

#### 한줄 요약
- 5단계는 인출→해독→연산→메모리→기록으로 각자 담당을 나누며, 단계 경계 레지스터가 클록마다 바통을 넘긴다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정상 상태(Steady State)**: 파이프라인 모든 단계에 유효 명령어가 채워져 매 클록 WB에서 결과가 나오는 상태.
- **플러시(Flush)**: 잘못 진행한 명령어를 무효화해 파이프라인에서 제거하는 복구 동작.

</details>

```text
클록     1    2    3    4    5    6    7
명령어A  IF   ID   EX  MEM   WB
명령어B       IF   ID   EX  MEM   WB
명령어C            IF   ID ─ 스톨 ─ EX  MEM  WB
명령어D                 IF ─ 스톨 ─ ID   EX  MEM
```

**동작 원리**

1. **투입**: 첫 명령어를 IF에 배치; 매 클록 후속 명령어를 뒤따라 투입
2. **단계 이동**: 클록마다 각 단계의 출력이 파이프라인 레지스터를 통해 다음 단계로 전달
3. **스톨**: 데이터 의존성·자원 충돌 시 해당 단계 이하를 정지하고 버블(NOP) 삽입
4. **플러시**: 분기 오예측 판정 후 잘못 투입된 명령어를 NOP으로 교체해 정확한 경로 재개

#### 한줄 요약
- 파이프라인은 채워지면 매 클록 결과가 나오지만, 스톨은 빈 슬롯을 만들고 플러시는 채운 슬롯을 버려 둘 다 처리량을 깎는다.

## Ⅴ. 종류 및 비교

| 실행 구조 | 5단계 파이프라인 | 비파이프라인 |
|:---|:---|:---|
| 적용 기준 | 높은 명령어 처리량 필요 | 단순 제어·작은 면적·결정적 지연 필요 |
| 핵심 특징 | 단계 중첩으로 **IPC** 최대화 | 한 명령어 순차 완료·기능 유닛 단순화 |
| 한계 | **스톨**·플러시·레지스터 오버헤드 | 낮은 처리량·기능 유닛 유휴 시간 발생 |

#### 한줄 요약
- 파이프라인은 여러 명령어를 겹쳐 처리하고, 비파이프라인은 하나가 끝난 뒤 다음을 시작해 처리량이 낮지만 설계가 단순하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 레지스터 기록 완료 전 ALU 결과를 후속 단계에 직접 전달하는 우회 경로.
- **분기 예측(Branch Prediction)**: 분기 결과를 미리 추정해 투기적으로 명령어를 계속 인출하는 기법.
- **단계 분할(Stage Splitting)**: 최장 단계의 긴 조합 논리 경로를 여러 짧은 단계로 나눠 클록 주기를 낮추는 설계 방법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 의존성으로 결과 미준비 시 **스톨** 발생 | **포워딩**과 스톨 제어 적용 | 불필요한 대기 사이클 감소·IPC 유지 |
| 분기 결과 지연으로 잘못된 명령어 진행 | **분기 예측**·오예측 시 플러시 | 제어 해저드 처리량 손실 완화 |
| **최장 단계 지연**으로 목표 주파수 미달 | **단계 분할**과 불균등 지연 분석 | 클록 주기 단축·처리량 향상 |
| 깊은 파이프라인의 플러시 복구 비용 급증 | 워크로드별 단계 깊이 조정 | 처리량·전력·복잡도 균형 확보 |

#### 한줄 요약
- 파이프라인은 무조건 깊게 나누는 것이 아니라, 스톨·플러시 비용과 클록 주기 이득을 비교해 적정 깊이를 결정해야 한다.

## Ⅶ. 결론

- 목표 **처리량**이 해저드 복구 비용보다 크면 파이프라이닝을 선택하고, **최장 단계 지연**·스톨 빈도·전력 비용을 함께 측정해 단계 깊이 결정

#### 한줄 요약
- 파이프라이닝의 성패는 단계 수가 아니라, 실제 워크로드에서 얻는 처리량이 스톨과 플러시 비용을 이기느냐에 달려 있다.
