## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **파이프라이닝(Pipelining)**: 명령 처리를 여러 단계로 나누고 서로 다른 명령어의 단계를 겹쳐 실행하여 처리량을 높이는 CPU 구조.
- **비파이프라인 구조(Non-Pipelined Architecture)**: 한 명령어의 모든 단계를 마친 뒤 다음 명령어를 시작해 단계가 중첩되지 않는 구조.

</details>

- 정의/개념: 서로 다른 명령어의 처리 단계를 중첩해 처리량을 높이는 CPU 명령어 처리 구조인 **파이프라이닝**
- 배경/필요성: **비파이프라인 구조**는 한 명령 실행 중 나머지 처리 회로가 유휴 상태여서 처리량 제한

#### 한줄 요약

- 명령어 실행 단계를 세분화하고 서로 다른 명령의 처리 단계를 중첩하여 단위시간당 명령 처리량(IPC)을 향상시키는 하드웨어 병렬 구조이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **처리량(Throughput)**: 단위 시간에 완료하는 명령어 수. 파이프라이닝이 직접 높이는 성능 지표.
- **지연시간(Latency)**: 명령어 하나가 인출부터 결과 기록까지 걸리는 시간. 단계 중첩만으로 반드시 줄지 않는 지표.
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 프로세서가 한 클록 주기에 완료하는 평균 명령어 수.
- **최장 단계 지연(Longest Stage Delay)**: 가장 오래 걸리는 처리 단계의 지연. 파이프라인의 최소 클록 주기를 결정.
- **단계 중첩(Stage Overlapping)**: 여러 명령이 같은 시점에 서로 다른 처리 단계를 점유하도록 실행을 겹치는 방식.

</details>

- **단계 중첩**으로 정상 상태에서 클록마다 명령 완료 가능
- **최장 단계 지연**이 파이프라인 최소 클록 주기 결정
- **지연시간**은 반드시 줄지 않지만 **단계 중첩**으로 **IPC**와 **처리량** 향상

#### 한줄 요약

- 개별 명령어 지연시간은 레지스터 지연으로 미증하거나 대등하지만, 전체 처리량(Throughput)은 단계 개수에 비례하여 증대한다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **명령어 인출(Instruction Fetch, IF)**: 메모리에서 다음 명령어를 가져오는 단계.
- **명령어 해독(Instruction Decode, ID)**: 명령을 해석하고 피연산자를 읽는 단계.
- **실행(Execute, EX)**: 연산과 메모리 주소 계산을 수행하는 단계.
- **메모리 접근(Memory Access, MEM)**: 데이터 메모리를 읽거나 쓰는 단계.
- **결과 기록(Write Back, WB)**: 연산 결과를 목적 레지스터에 저장하는 단계.
- **파이프라인 레지스터(Pipeline Register)**: 각 단계의 중간 결과와 제어 신호를 다음 클록에 후속 단계로 전달하는 저장 회로.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터.
- **산술논리장치(Arithmetic Logic Unit, ALU)**: EX 단계에서 연산과 주소 계산을 수행하는 장치.

</details>

```text
5단계 파이프라인 데이터 경로
├─ 단계 처리 회로
│  ├─ IF·ID·EX·MEM·WB
└─ 파이프라인 레지스터
   ├─ IF/ID·ID/EX
   └─ EX/MEM·MEM/WB
```

가지의 의미: 단계 처리 회로와 단계 사이 상태 저장 회로의 소유 관계.

| 구성요소 | 책임                                 |
| :------- | :----------------------------------- |
| 단계 처리 회로 | **PC** 기반 IF 인출•ID 해독•**ALU** 기반 EX 연산•MEM 접근•WB 기록 수행 |
| 파이프라인 레지스터 | 단계별 중간값•제어 신호를 클록 경계에서 보관 |

> 요약: 단계 사이 **파이프라인 레지스터**로 명령별 중간 상태 격리.

#### 한줄 요약

- IF부터 WB까지 각 단계가 서로 다른 명령을 동시에 처리해 완료 처리량을 높인다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **데이터 경로(Data Path)**: 명령 처리 값이 메모리·레지스터·연산기 사이를 이동하는 하드웨어 경로.
- **레지스터 파일(Register File)**: ID 단계에서 피연산자를 제공하고 WB 단계에서 결과를 저장하는 범용 레지스터 묶음.
- **IF/ID 파이프라인 레지스터**: IF 결과를 클록 경계에서 ID로 전달하는 레지스터.
- **ID/EX 파이프라인 레지스터**: ID 결과를 클록 경계에서 EX로 전달하는 레지스터.
- **제어 신호(Control Signal)**: 해독한 명령에 맞춰 연산·메모리 접근·결과 기록 동작을 지정하는 비트 값.

</details>

```text
명령어 n   : IF → ID → EX → MEM → WB
명령어 n+1 :      IF → ID → EX  → MEM → WB
명령어 n+2 :           IF → ID  → EX  → MEM → WB
```

- 각 클록에서 단계별 결과를 **파이프라인 레지스터**에 저장하고 다음 단계로 전달.
- **데이터 경로**의 **레지스터 파일** 값과 **제어 신호**는 **IF/ID 파이프라인 레지스터**•**ID/EX 파이프라인 레지스터**를 거쳐 명령별 분리.

#### 한줄 요약

- 단계 사이 파이프라인 레지스터가 중간 결과와 제어 신호를 분리해 여러 명령이 서로 다른 단계를 동시에 점유하게 한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **해저드(Hazard)**: 자원 충돌이나 명령 간 의존성 때문에 다음 파이프라인 단계로 진행할 수 없는 상태.
- **버블(Bubble)**: 해저드로 유효한 명령을 투입하지 못해 파이프라인에 생기는 빈 처리 주기.
- **플러시(Flush)**: 분기 예측 실패 시 잘못 인출한 명령을 무효화하고 올바른 경로를 다시 채우는 동작.
- **긴 주기(Long Cycle)**: 한 명령의 전체 조합 회로 지연을 한 클록에 수용해 클록 주기가 길어지는 비파이프라인 특성.

</details>

| 명령 실행 구조 | 5단계 파이프라인               | 비파이프라인                    |
| :------------- | :----------------------------- | :------------------------------ |
| 적용 기준      | 연속 명령의 높은 **처리량** 필요 시 | 회로 면적과 제어 단순성 우선 시 |
| 핵심 특징      | 서로 다른 명령의 **단계 중첩** | 한 명령의 모든 단계 순차 완료 |
| 한계           | **해저드**에 따른 **버블**•**플러시** | 전 경로를 합친 **긴 주기** |

> 요약: 처리량 이득과 해저드 손실 비교.

#### 한줄 요약

- Pipeline Stage Overlapping을 통해 ideal IPC 1을 달성하나, Structural/Data/Control Hazard 발생 시 Pipeline Bubble 및 Flush Penalty가 수반된다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **포워딩(Forwarding)**: 앞 명령의 결과를 레지스터 기록 전에 뒤 명령 입력으로 직접 전달하여 데이터 대기를 줄이는 기법.
- **분기 예측(Branch Prediction)**: 분기 결과 확정 전에 다음 실행 경로를 예측하여 명령어 인출을 계속하는 기법.
- **해저드 검출기(Hazard Detector)**: 명령 간 충돌을 찾아 파이프라인 정지•우회•플러시를 제어하는 회로.
- **명령 스케줄링(Instruction Scheduling)**: 의존성이 없는 명령의 순서를 조정해 데이터 대기와 버블을 줄이는 기법.
- **조기 판정(Early Resolution)**: 분기 조건과 목적지를 앞 단계에서 확정해 잘못 인출하는 명령 수를 줄이는 기법.
- **단계 분할(Stage Splitting)**: 긴 처리 단계를 여러 단계로 나누는 방법.
- **회로 재배치(Logic Redistribution)**: 조합 논리를 다른 단계로 옮겨 지연을 균등화하는 방법.
- **단계 사용률(Stage Utilization)**: 각 파이프라인 단계가 유효한 명령을 처리한 시간의 비율. 병목과 유휴 구간을 찾는 지표.
- **우회 경로(Bypass Path)**: 연산 결과를 정규 저장 경로보다 먼저 의존 명령의 입력으로 전달하는 하드웨어 경로.

</details>

| 문제                                | 대책                                    | 효과                               |
| :---------------------------------- | :-------------------------------------- | :--------------------------------- |
| 명령 의존으로 버블 증가 | **포워딩**•**우회 경로**•**해저드 검출기**와 **명령 스케줄링** | 피연산자 대기 감소 |
| 분기 오예측으로 플러시 증가 | **분기 예측**•**조기 판정** 개선 | 잘못 인출한 명령 수 감소 |
| 특정 단계 지연이 클록 주기 지배 | **단계 분할**•**회로 재배치** | 최장 단계 단축 |
| 파이프라인 심화 후에도 IPC 정체 | **버블**•**플러시**•**단계 사용률** 측정 | 처리량 제한 원인 식별 |

#### 한줄 요약

- Data Forwarding, Branch Prediction, Stage Balancing(최장 Delay 단축)을 통합 적용하여 Pipeline Stall/Flush를 최소화한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **파이프라인 개선 기준**: 최장 단계 지연과 버블•플러시가 각각 클록 주기와 IPC에 미치는 영향으로 개선 대상을 정하는 기준.

</details>

- **파이프라인 개선 기준**에 따라 클록 주기 병목은 **최장 단계 지연**, IPC 손실은 **버블**•**플러시** 우선 개선

#### 한줄 요약

- $\text{Execution Time} = \text{IC} \times \text{CPI} \times \text{Clock Cycle Time}$ 공식에 입각하여 CPI(Bubble/Flush 감소)와 Clock Cycle Time(Stage Delay 균등화)을 동시 최적화한다.
