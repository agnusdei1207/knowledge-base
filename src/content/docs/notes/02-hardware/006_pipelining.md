## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라이닝(Pipelining)**: 명령어를 인출, 해독, 실행 등 복수의 단계로 분할하고 단계를 겹쳐 실행하여 처리량을 높이는 하드웨어 병렬 기법이다.
- **비파이프라인 구조(Non-Pipelined Architecture)**: 한 명령어의 모든 실행 단계가 완결될 때까지 후속 명령어의 진입을 대기시키는 순차 실행 아키텍처이다.
- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 프로세서가 단일 클록 주기에 완료하여 출력하는 평균 기계어 명령어 수이다.
- **파이프라인 단계(Pipeline Stage)**: 명령어가 처리되는 세부 하드웨어 분할 단위이다.

</details>

- 정의: 명령어 처리 과정을 세부 단계로 분할하고 처리 단계를 중첩하여 병렬로 실행하는 **파이프라이닝** 하드웨어 구조
- 배경: 단일 **비파이프라인 구조**에서 발생하는 하드웨어 유휴 상태를 해소하고 **클록당 명령어 수**를 극대화하기 위함

#### 한줄 요약

- 명령어 실행을 복수 단계로 중첩하여 단위 시간당 명령어 처리량을 극대화하는 하드웨어 병렬 구조이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **처리량(Throughput)**: 단위 시간 동안 파이프라인 최종 단계를 빠져나와 완료되는 기계어 명령어의 총량이다.
- **지연시간(Latency)**: 단일 명령어의 인출 시작부터 결과가 레지스터에 기록될 때까지 소요되는 총 시간이다.
- **최장 단계 지연(Longest Stage Delay)**: 단계 중 가장 논리 지연 시간이 길어 시스템 전체 클록 주기를 제약하는 구간이다.
- **단계 중첩(Stage Overlapping)**: 동일 클록 주기에 서로 다른 명령어가 각 단계를 시분할로 점유하는 동작이다.

</details>

- **단계 중첩** 기법을 활용하여 정상 상태 진입 시 매 클록마다 1개의 명령어 처리를 완료함.
- 동작의 최소 클록 주기는 가장 지연이 긴 **최장 단계 지연**과 파이프라인 레지스터 지연의 합에 의해 한정됨.
- 개별 명령어의 **지연시간**은 레지스터 지연으로 미세하게 증가하지만 전체 **처리량**은 단계 수에 비례하여 향상됨.

#### 한줄 요약

- 개별 지연은 늘어날 수 있으나 단계 중첩으로 전체 처리량을 대폭 높인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch, IF)**: 프로그램 카운터가 지시하는 메모리 주소에서 기계어를 읽고 주소를 증가시키는 1단계이다.
- **명령어 해독(Instruction Decode, ID)**: 오퍼코드를 디코딩하고 범용 레지스터에서 피연산자를 읽는 2단계이다.
- **실행(Execute, EX)**: 산술 논리 계산을 진행하거나 메모리 접근을 위한 실효 주소를 계산하는 3단계이다.
- **메모리 접근(Memory Access, MEM)**: 데이터 메모리에 직접 접근하여 읽기 쓰기를 수행하는 4단계이다.
- **결과 기록(Write Back, WB)**: 연산 결과나 메모리 로드 값을 목표 레지스터에 기록하는 5단계이다.
- **파이프라인 레지스터(Pipeline Register)**: 각 단계 사이에 위치하여 중간 결과와 제어 신호를 동기화 전달하는 레지스터이다.

</details>

```text
[ 기본 RISC 파이프라인 5단계 ]
  +------+    +------+    +------+    +------+    +------+
  |  IF  |===>|  ID  |===>|  EX  |===>| MEM  |===>|  WB  |
  +------+    +------+    +------+    +------+    +------+
     ||          ||          ||          ||          ||
  [IF/ID]     [ID/EX]     [EX/MEM]    [MEM/WB] (파이프라인 레지스터)
```

| 구성요소 | 책임 |
|:---|:---|
| **명령어 인출** | 프로그램 카운터 기반 기계어 인출 및 주소 갱신 |
| **명령어 해독** | 명령어 해독과 피연산자 및 제어 신호 생성 |
| **실행** | 산술 논리 연산 수행 및 분기 주소 계산 |
| **메모리 접근** | 로드 및 스토어 명령어의 데이터 캐시 접근 |
| **결과 기록** | 연산 결과 및 로드 데이터의 레지스터 기록 |
| **파이프라인 레지스터** | 단계 간 데이터 및 제어 신호의 동기화 전달 |

#### 한줄 요약

- 인출부터 기록까지 5단계 구조와 이를 격리하는 파이프라인 레지스터를 통해 파이프라인 동기화 제어를 수행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 경로(Data Path)**: 연산 결과가 단계별 레지스터와 연산기를 거쳐 흐르는 통로이다.
- **레지스터 파일(Register File)**: 입력값을 읽어오고 최종 결과를 기록하는 멀티포트 저장 블록이다.
- **제어 신호(Control Signal)**: 생성되어 단계를 이동하며 부품의 동작을 통제하는 비트열이다.

</details>

```text
클록 주기 ──>   CC1   CC2   CC3   CC4   CC5   CC6   CC7
명령어 1:      IF ──> ID ──> EX ──> MEM ──> WB
명령어 2:             IF ──> ID ──> EX  ──> MEM ──> WB
명령어 3:                    IF ──> ID  ──> EX  ──> MEM ──> WB
명령어 4:                           IF  ──> ID  ──> EX  ──> MEM ──> WB
```

### 동작 원리

1. 시동 단계: 초기 클록 주기에 순차적으로 명령어를 투입하여 파이프라인 단계를 채움.
2. 정상 상태: 모든 단계가 채워진 후 매 클록마다 1개의 명령어가 완료됨.
3. 제어 신호 이동: 클록 엣지마다 파이프라인 레지스터가 다음 단계로 **제어 신호**를 전달함.
4. 결과 갱신: 최종 단계에서 **레지스터 파일**에 결과를 기록하고 사이클을 반복함.

#### 한줄 요약

- 시동 단계를 거쳐 정상 상태에 도달하면 매 클록마다 명령어가 완료되는 중첩 흐름을 형성한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **해저드(Hazard)**: 파이프라인에서 자원 경합이나 데이터 의존성으로 인해 명령어를 계속 실행하지 못하는 구조적 장애이다.
- **버블(Bubble)**: 해저드 발생 시 파이프라인에 아무 연산도 없는 신호를 주입하여 1클록 멈추게 하는 지연 기법이다.
- **플러시(Flush)**: 분기 예측 실패 시 이미 파이프라인에 진입한 하위 명령어들을 파기하는 작업이다.
- **긴 주기(Long Cycle Time)**: 비파이프라인에서 모든 회로 지연을 합산하여 결정되는 가장 긴 클록 주기이다.

</details>

| 비교 항목 | 5단계 파이프라인 아키텍처 | 비파이프라인 아키텍처 |
|:---|:---|:---|
| 클록 주기 | **최장 단계 지연**에 따른 짧은 주기 | 전 과정 합산 지연으로 구성된 **긴 주기** |
| 처리량 | 이상적 상태에서 매우 높은 처리량 | 단일 처리로 인해 처리량 저하 |
| 회로 복잡도 | 레지스터 포워딩 및 **해저드** 제어 추가 | 해저드 제어 회로 불필요 |
| 장애 요소 | 의존성에 따른 **버블** 및 예측 실패 시 **플러시** | 해저드 및 버블이 원천적으로 발생하지 않음 |

#### 한줄 요약

- 비파이프라인의 긴 클록 주기를 극복하여 처리량을 높이지만 해저드 제어를 위한 오버헤드가 발생한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 연산 결과를 레지스터 저장을 기다리지 않고 다음 입력으로 즉시 연결하는 하드웨어 기술이다.
- **분기 예측(Branch Prediction)**: 타깃이 확정되기 전에 다음 명령어 주소를 예측 구동하여 분기 지연을 줄이는 기술이다.
- **명령 스케줄링(Instruction Scheduling)**: 컴파일러가 데이터 의존성이 없는 명령어를 재배치하는 최적화 기법이다.
- **단계 분할(Stage Splitting)**: 논리 지연이 긴 단계를 미세 단계로 나누어 클록 주파수를 높이는 기법이다.
- **단계 사용률(Stage Utilization)**: 파이프라인 각 단계가 유효한 명령을 실행하는 비율이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 의존성 데이터 해저드 발생 및 **버블** 주입 | **포워딩** 경로 구성 및 컴파일러 **명령 스케줄링** 적용 | 대기 버블 축소 및 연산 주파수 유지 |
| 조건 분기 타깃 미확정으로 파이프라인 **플러시** 손실 | 버퍼 기반 **분기 예측** 및 조기 판정 회로 내장 | 분기 페널티를 최소화하고 연속성 보장 |
| 특정 논리 지연이 길어 클록 주파수 저하 | 지연 경로를 분할하는 **단계 분할** 및 회로 재배치 | 클록 주파수 상승으로 전체 성능 향상 |
| 단계 깊이 증가에 따른 **단계 사용률** 저하 | 동적 해저드 제어 및 비순차 실행 엔진 연동 | 버블 최소화 및 단위 시간 유효 처리량 극대화 |

#### 한줄 요약

- 데이터 포워딩, 분기 예측, 단계 분할 및 명령 스케줄링을 통해 파이프라인 정지와 파기 오버헤드를 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **파이프라인 개선 기준(Pipeline Optimization Criteria)**: 파이프라인 깊이, 해저드 통제, 클록 속도의 균형을 수립하는 평가 지표이다.

</details>

- 분기 페널티가 크면 **분기 예측**, 단계 지연이 길면 **단계 분할** 등 **파이프라인 개선 기준** 적용

#### 한줄 요약

- 성능 저하 요인과 최장 단계 지연을 측정하여 해저드 제어 기법과 파이프라인 깊이를 최적화해야 한다.
