## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라이닝(Pipelining)**: 명령어 처리 과정을 여러 하위 단계로 세분화하고, 서로 다른 명령어를 클록마다 병렬로 중첩 실행하여 시스템의 전체 처리량을 극대화하는 하드웨어 설계 기법이다.
- **처리량(Throughput)**: 단위 시간당 중앙처리장치가 처리를 완료하여 파이프라인을 빠져나가는 총 명령어 수이다.
- **지연시간(Latency)**: 단일 명령어가 파이프라인의 첫 단계인 명령어 인출부터 마지막 단계인 결과 기록까지 전체 경로를 통과하는 데 소요되는 총 시간이다.

</details>

- 정의/개념: 명령어 처리를 여러 단계로 쪼개 서로 다른 명령어가 매 클록 다른 단계를 점유하게 만드는 **파이프라이닝** 구조
- 배경/필요성: 명령어를 하나씩 끝까지 처리하면 나머지 기능 유닛이 매 클록 놀게 되어 **처리량**이 회로 규모에 비해 낮음

#### 한줄 요약
- 파이프라이닝은 명령어 하나의 **지연시간**을 오히려 늘리면서 전체 처리량을 얻는 거래이며, 응답 시간이 목표인 설계에서는 이 거래가 손해가 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: CPU가 단일 클록 사이클당 평균적으로 완료하는 명령어 수(이상적 단일 파이프라인에서 IPC=1).
- **최장 단계 지연(Critical Path Delay)**: 파이프라인 단계 중 조합 논리 회로의 전파 지연이 가장 긴 단계의 지연 시간으로, 전체 프로세서의 최대 클록 주파수를 결정.
- **스톨(Stall)**: 해저드 발생 시 파이프라인 특정 단계의 전진을 멈추고 파이프라인 버블(NOP)을 삽입하여 대기시키는 제어 동작.

</details>

- 단계 중첩으로 **IPC**를 1에 가깝게 높여 처리량 향상
- **최장 단계 지연**이 전체 클록 주기를 결정해 단계 균등 분할이 중요
- 해저드 발생 시 **스톨**·플러시로 유효 명령어 완료율 감소

#### 한줄 요약
- 단계를 늘리면 클록은 빨라지지만 스톨 한 번의 손실도 같이 커지므로, 이득과 손실이 뒤집히는 지점이 파이프라인 깊이의 상한이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch, IF)**: PC가 가리키는 메모리 주소에서 명령어를 읽어와 IF/ID 파이프라인 레지스터에 적재하고 PC를 갱신하는 단계.
- **명령어 해독(Instruction Decode, ID)**: 명령어의 Opcode와 피연산자를 해독하고 레지스터 파일에서 피연산자 값을 읽어오는 단계.
- **실행(Execute, EX)**: ALU를 통해 산술/논리 연산 수행, 메모리 유효 주소 계산, 분기 조건 판정 및 목표 주소 계산을 수행하는 단계.
- **메모리 접근(Memory Access, MEM)**: 데이터 메모리에 접근하여 로드(Load) 데이터를 읽거나 스토어(Store) 데이터를 쓰는 단계.
- **결과 기록(Write Back, WB)**: ALU 연산 결과 또는 메모리에서 로드한 데이터를 최종 목적 레지스터 파일에 기록하는 단계.
- **파이프라인 레지스터(Pipeline Register)**: 인접한 파이프라인 단계 경계(IF/ID, ID/EX, EX/MEM, MEM/WB) 사이에 위치하여 데이터와 제어 신호를 매 클록마다 래치(Latch)하는 동기화 레지스터.

</details>

```text
[5단계 파이프라인]
  IF ── ID ── EX ── MEM ── WB
  │    │    │     │      │
IF/ID ID/EX EX/MEM MEM/WB (파이프라인 레지스터)
```

선의 의미: `──`는 단계 순서 연결; `│` 아래는 단계 경계의 파이프라인 레지스터

| 구성요소 | 책임 |
|:---|:---|
| IF | 프로그램 카운터 기반 명령어 인출·주소 증가 |
| ID | 명령어 해독·레지스터 피연산자 준비 |
| EX | ALU 연산·주소 계산·분기 조건 평가 |
| MEM | 로드·스토어 데이터 메모리 접근 |
| WB | 연산·로드 결과 레지스터 기록 |
| **파이프라인 레지스터** | 단계별 데이터와 제어 정보를 클록 단위로 보관 |

#### 한줄 요약
- 단계를 나눈 비용은 경계마다 추가되는 레지스터이며, 깊게 나눌수록 그 레지스터가 차지하는 면적과 전력이 성능 이득을 잠식한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정상 상태(Steady State)**: 파이프라인의 모든 단계에 유효한 명령어가 가득 차 매 클록 사이클마다 결과 기록(WB) 단계에서 명령어가 완료되는 동작 상태.
- **플러시(Flush)**: 분기 오예측 또는 예외 발생 시 파이프라인 내부에 이미 진입한 무효한 명령어들을 NOP 처리하여 비우는 제어 동작.

</details>

```text
명령어가 다음 단계로 진입 요청
        │
   진행을 막는 요인이 있는가?
 ┌──────┼─────────────┐
없음      의존성·자원 경합    분기 오예측 확정
 │           │                │
단계 전진   스톨: 해당 단계와   플러시: 진입한
 │        이전 단계 동결      명령어 무효화
 │           │                │
 │      원인 해소 후 재개    올바른 주소에서 재인출
 └──────┬────┘                │
        │                     │
   정상 상태 유지          파이프라인 재충전
```

분기 결과: 스톨은 이미 채운 슬롯을 붙잡아 두는 손실이고 플러시는 채운 슬롯을 버리는 손실이라, 같은 한 사이클이라도 깊은 파이프라인에서는 플러시 쪽이 훨씬 비쌈

#### 한줄 요약
- 스톨 손실은 단계 수와 무관하지만 플러시 손실은 단계 수에 비례하므로, 파이프라인이 깊어질수록 분기 예측의 중요도가 데이터 우회보다 커진다.

## Ⅴ. 종류 및 비교

| 실행 구조 | 5단계 파이프라인 | 비파이프라인 |
|:---|:---|:---|
| 적용 기준 | 높은 명령어 처리량 필요 | 단순 제어·작은 면적·결정적 지연 필요 |
| 핵심 특징 | 단계 중첩으로 **IPC**를 1에 근접 | 명령어를 하나씩 완료해 기능 유닛 단순화 |
| 한계 | **스톨**·플러시 손실과 경계 레지스터 비용 | 낮은 처리량과 기능 유닛 유휴 시간 |

#### 한줄 요약
- 비파이프라인이 남아 있는 이유는 처리량을 포기해서가 아니라, 명령어마다 실행 시간이 항상 같다는 성질이 실시간 제어에서는 처리량보다 값지기 때문이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어의 결과가 레지스터에 기록(WB)되기 전에 ALU 출력 또는 메모리 버퍼에서 후속 명령어의 실행 입력(EX)으로 직접 우회 전달하는 기법.
- **분기 예측(Branch Prediction)**: 분기 명령어의 실행 결과(방향 및 목표 주소)가 확정되기 전에 미리 추측하여 후속 명령어 인출을 중단 없이 지속하는 기법.
- **단계 분할(Stage Splitting)**: 임계 경로 지연이 큰 파이프라인 단계를 더 작은 하위 단계로 분할하여 전체 시스템 클록 주파수를 향상시키는 설계 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 의존성으로 결과 미준비 시 **스톨** 발생 | **포워딩**과 스톨 제어 적용 | 불필요한 대기 사이클 감소·IPC 유지 |
| 분기 결과 지연으로 잘못된 명령어 진행 | **분기 예측**·오예측 시 플러시 | 제어 해저드 처리량 손실 완화 |
| **최장 단계 지연**으로 목표 주파수 미달 | **단계 분할**과 불균등 지연 분석 | 클록 주기 단축·처리량 향상 |
| 깊은 파이프라인의 플러시 복구 비용 급증 | 워크로드별 단계 깊이 조정 | 처리량·전력·복잡도 균형 확보 |

#### 한줄 요약
- 네 대책은 모두 단계를 더 나누는 대신 나눈 대가를 줄이는 쪽이며, 깊이를 늘리는 결정은 이 대가를 감당할 수 있을 때만 성립한다.

## Ⅶ. 결론

- 스톨·플러시를 포함한 실효 IPC가 높으면 **파이프라이닝**을 적용하고, 결정적 지연과 제어 단순성이 우선이면 비파이프라인 구조 유지

#### 한줄 요약
- 이상적 IPC는 설계도에서만 성립하고 실제로는 워크로드의 분기 비율과 의존성 밀도가 결정하므로, 깊이 선택은 회로가 아니라 코드를 보고 해야 한다.
