## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **파이프라이닝(Pipelining)**: 명령어 처리를 여러 단계로 나누고 서로 다른 명령어의 단계를 겹쳐 실행하는 기법입니다.
- **처리량(Throughput)**: 단위 시간에 시스템이 완료하는 명령어 또는 작업의 양입니다.
- **지연시간(Latency)**: 하나의 명령어가 시작부터 완료까지 걸리는 시간입니다.

</details>

- 정의/개념: 명령어 단계를 중첩해 **처리량**을 높이는 CPU 실행 구조
- 배경/필요성: 기능 유닛 유휴 시간과 긴 조합 논리 경로 완화

#### 한줄 요약

- 파이프라이닝은 한 명령어를 더 빨리 끝내기보다, 여러 명령어가 각자 다른 공정을 동시에 지나게 해 전체 완료 수를 높입니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클록당 명령어 수(Instructions Per Cycle, IPC)**: 평균 한 클록에 완료하는 명령어의 수입니다.
- **최장 단계 지연(Longest Stage Delay)**: 단계 중 가장 오래 걸려 전체 클록 주기를 제한하는 지연입니다.
- **파이프라인 레지스터 오버헤드(Pipeline Register Overhead)**: 단계 사이 레지스터가 추가하는 저장과 타이밍 비용입니다.

</details>

- 여러 명령어 단계의 **동시 중첩 처리**
- 최장 단계 지연에 따른 **클록 주기 제한**
- 스톨이 없을 때 IPC 1에 가까운 **처리량 향상**

#### 한줄 요약

- 모든 단계의 시간이 고르게 짧고 멈춤이 적을수록, 파이프라인은 매 클록마다 명령어 하나를 끝낼 수 있습니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **명령어 인출(Instruction Fetch, IF)**: 프로그램 카운터를 바탕으로 다음 명령어를 가져오는 단계입니다.
- **명령어 해독(Instruction Decode, ID)**: 명령어 의미와 피연산자, 제어 정보를 준비하는 단계입니다.
- **실행(Execute, EX)**: 산술·논리 연산, 주소 계산, 분기 조건 평가를 수행하는 단계입니다.
- **메모리 접근(Memory Access, MEM)**: 로드·스토어 명령어의 데이터 메모리 접근을 수행하는 단계입니다.
- **결과 기록(Write Back, WB)**: 연산 또는 로드 결과를 레지스터에 기록하는 단계입니다.
- **파이프라인 레지스터(Pipeline Register)**: 단계 경계에서 데이터와 제어 정보를 저장하는 레지스터입니다.

</details>

```text
[5단계 파이프라인]
├─ IF
├─ ID
├─ EX
├─ MEM
├─ WB
└─ 파이프라인 레지스터
```

| 구성요소 | 책임 |
|:---|:---|
| IF | PC 기반 명령어 인출 |
| ID | 명령어 해독과 피연산자 준비 |
| EX | 산술·논리 연산과 주소 계산 |
| MEM | 로드·스토어 데이터 접근 |
| WB | 결과의 레지스터 기록 |
| 파이프라인 레지스터 | 단계별 데이터·제어 정보 보관 |

#### 한줄 요약

- 5단계 파이프라인은 명령어를 가져오고 이해하고 계산하고 메모리를 읽고 결과를 쓰는 일을 나눠 맡습니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정상 상태(Steady State)**: 파이프라인이 채워져 모든 단계가 유효한 명령어를 처리하는 상태입니다.
- **스톨(Stall)**: 의존성이나 자원 부족으로 한 단계의 진행을 잠시 멈추는 제어입니다.
- **플러시(Flush)**: 잘못 진행한 명령어를 무효화해 파이프라인에서 제거하는 제어입니다.

</details>

```text
명령어       1클록  2클록  3클록  4클록  5클록
명령어 A       IF     ID     EX    MEM    WB
명령어 B              IF     ID     EX    MEM
명령어 C                     IF     ID     EX
```

동작 원리:

1. 투입: 첫 명령어를 IF에 배치
2. 단계 이동: 클록마다 다음 단계의 레지스터로 정보 전달
3. 중첩 실행: 서로 다른 명령어가 각 단계에서 동시 처리
4. 완료: 정상 상태에서는 매 클록 WB에서 결과 기록

#### 한줄 요약

- 공장 조립선처럼 앞 명령어가 다음 단계로 갈 때 뒤 명령어가 빈 자리에 들어오므로, 채워진 뒤에는 완료가 연속됩니다.

## Ⅴ. 종류 및 비교

| 실행 구조 | 5단계 파이프라인 | 비파이프라인 |
|:---|:---|:---|
| 적용 기준 | 높은 명령 처리량 필요 | 단순 제어와 작은 구현 필요 |
| 핵심 특징 | 단계 중첩과 단계별 레지스터 | 한 명령어의 순차 완료 |
| 한계 | 스톨·플러시·레지스터 오버헤드 | 낮은 처리량과 유휴 자원 |

#### 한줄 요약

- 같은 일을 해도 파이프라인은 여러 명령어를 겹쳐 처리하고, 비파이프라인은 하나가 끝난 뒤 다음 일을 시작합니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 이전 명령어의 결과를 레지스터 기록 전에 다음 단계로 직접 전달하는 우회 경로입니다.
- **분기 예측(Branch Prediction)**: 분기 결과를 미리 추정해 다음 명령어 인출을 이어가는 기법입니다.
- **단계 분할(Stage Splitting)**: 긴 조합 논리 경로를 여러 짧은 단계로 나누는 설계 방법입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 의존성으로 다음 단계 진행 정지 | 포워딩과 스톨 제어 적용 | 불필요한 대기 사이클 감소 |
| 분기 결과가 늦어 잘못된 명령 진행 | 분기 예측과 플러시 복구 적용 | 제어 흐름 손실 완화 |
| 특정 단계가 길어 클록 주기 증가 | 단계 분할과 오버헤드 분석 | 목표 주파수와 지연 균형 |
| 깊은 단계로 복구 비용과 전력 증가 | 워크로드별 파이프라인 깊이 조정 | 처리량·전력·복잡도 균형 |

#### 한줄 요약

- 파이프라인은 무조건 깊게 나누는 구조가 아니라, 멈춤과 복구 비용을 줄일 수 있는 깊이에서 설계해야 합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **해저드(Hazard)**: 명령어 중첩 때문에 데이터, 자원, 제어 흐름이 예정대로 진행되지 못하는 상황입니다.

</details>

- 목표 **처리량**이 해저드 복구 비용보다 크면 파이프라이닝을 선택하고, 최장 단계 지연·**해저드**·전력 비용을 함께 측정해 단계 깊이 결정

#### 한줄 요약

- 파이프라이닝의 성패는 단계 수가 아니라, 실제 프로그램에서 얻는 처리량이 멈춤과 복구 비용을 이기는지에 달려 있습니다.
