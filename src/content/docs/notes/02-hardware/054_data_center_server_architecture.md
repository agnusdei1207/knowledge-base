## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터센터 서버 아키텍처(Data Center Server Architecture)**: 연산, 메모리, 스토리지, I/O 및 전원/냉각 계층을 랙 단위 인프라와 결합하여 최적화한 엔터프라이즈 하드웨어 시스템.
- **서버 노드(Server Node)**: 단일 섀시(1U/2U/4U) 내에 프로세서, 메모리, 확장 슬롯 및 전원 공급 장치를 집적한 독립 실행 단위.
- **Failure Domain(장애 범위)**: 단일 부품(PSU, Fan, NIC) 고장 시 서비스 중단이 파급되는 물리적/논리적 영향 반경.

</details>

- 정의/개념: 데이터센터 랙(Rack) 및 인프라 환경 내에서 연산(CPU/GPU), 메모리(DRAM/CXL), 스토리지(NVMe SSD), 네트워크(SmartNIC/DPU) 및 전원/냉각 계층을 최적 비율로 통합 구성한 엔터프라이즈 서버 하드웨어 시스템 구조
- 배경/필요성: 단일 부품의 처리량 증가만으로는 극복할 수 없는 **I/O 병목, NUMA 원격 지연, 랙 전력 밀도(kW/Rack) 한계 및 단일 장애점(SPOF)을 제거하고 고가용성 확보**

#### 한줄 요약

- 연산·메모리·I/O·전원/냉각의 **균형 잡힌 계층 설계로 고성능 및 고가용성 데이터센터 인프라 구현**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Rack Power Density(랙 전력 밀도)**: 랙 1대당 수용 가능한 최대 전력량(일반 랙 10~15kW, AI 가속 랙 40~100+kW).
- **Out-of-Band Management(대역 외 관리)**: 주 서비스 네트워크와 물리적으로 분리된 전용 관리망을 통해 BMC(Baseboard Management Controller)로 서버를 원격 제어하는 방식.

</details>

- 연산(FLOPs), 메모리(GB/s), I/O(Gbps) 간의 균형 배치를 통한 **종단 병목(End-to-End Bottleneck) 해소**
- 랙 전력 밀도 한도 내에서 칩 열화를 방지하고 고성능을 유지하는 **고밀도 패키징 및 액체 냉각(Direct Liquid Cooling)** 적용
- 메인 OS 장애 시에도 원격 전원 제어 및 모니터링이 가능한 **대역 외(Out-of-Band) 관리망 및 장애 격리(Fault Isolation)**

#### 한줄 요약

- **컴포넌트 밸런싱(종단 병목 해소)·랙 전력 밀도/액체 냉각 관리·OOB 관리망 기반 장애 격리**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: OS 상태와 무관하게 IPMI/Redfish 프로토콜로 전원 제어, 팬 속도 조절, 펌웨어 갱신을 수행하는 온보드 관리 프로세서.
- **DPU/SmartNIC**: 호스트 CPU 대신 네트워크 패킷 암호화, 스토리지 가상화, 보안 정책 처리를 오프로드하는 전용 I/O 프로세서.

</details>

```text
[ 데이터센터 서버 계층 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 연산 계층 (Compute Layer) : CPU (x86/ARM) + GPU/NPU 가속기│
└──────────────────────────────┬──────────────────────────────┘
                               │ [ UPI / PCIe Gen5 / CXL ]
┌──────────────────────────────┴──────────────────────────────┐
│ 2. 메모리 / 스토리지 계층 : DDR5 DRAM + CXL 풀링 + NVMe SSD │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ PCIe 톨게이트 ]
┌──────────────────────────────┴──────────────────────────────┐
│ 3. 네트워크 / I/O 계층 : 100/400GbE SmartNIC / DPU / HCA     │
└─────────────────────────────────────────────────────────────┘
═══════════════════════════════╤═══════════════════════════════ (인프라 지원 계층)
┌──────────────────────────────┴──────────────────────────────┐
│ 4. 파워 / 냉각 계층 : 이중화 PSU (N+1/2N) + 고속 Fan / 수랭 │
│ 5. 대역 외 관리 계층 : 독립 OOB 포트 + BMC 칩셋 (Redfish)   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 연산 계층(CPU/GPU), 메모리/스토리지 계층, 네트워크/I/O(SmartNIC), 파워/냉각 계층 및 대역 외 관리 계층(BMC) 간의 서버 시스템 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 연산 계층 블록 | CPU와 GPU를 때려 박아 범용 비즈니스 로직 연산과 무식한 딥러닝 텐서 폭격을 전담하여 처리 |
| 메모리 스토리지 계층 | 연산기 입에 데이터를 퍼 먹이는 주메모리(DRAM)와 영구 보관용 고속 SSD 스토리지 밥줄 제공 |
| 네트워크 아이오 계층 | 서버 밖으로 패킷을 미친 듯이 쏘아대고 외부 세계와 통신하는 이더넷 및 PCIe 버스 톨게이트 통제 |
| 파워 및 냉각 인프라 | 비싼 부품들이 전력 부족으로 뻗거나 열기에 타죽지 않도록 파워 서플라이 전압 분배 및 강풍 쿨링 방열 수행 |
| 대역 외 관리 계층 | 서버 OS가 뻗어도 딴 선으로 접속해 강제로 전원을 껐다 켤 수 있는 **베이스보드 관리 컨트롤러**(BMC) 원격 감시 제어 |

#### 한줄 요약

- **연산 계층(CPU/GPU)·메모리/스토리지(CXL/NVMe)·네트워크(DPU)·파워/냉각·대역 외 관리(BMC)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NUMA Local Access**: CPU 코어가 동일 소켓에 연결된 로컬 메모리 컨트롤러를 통해 최저 지연으로 데이터에 접근하는 방식.

</details>

```text
[ 서버 내부 자원 처리 및 I/O 디스패치 흐름 ]
                         │
                         ▼
   [ 1. 네트워크 SmartNIC/DPU로 외부 요청 패킷 유입 ]
                         │
                         ▼
   [ 2. 최적 소켓의 로컬 메모리로 DMA 직접 전송 (NUMA 로컬 인출) ]
                         │
                         ▼
   [ 3. 워크로드 특성 분석 (범용 비즈니스 로직 vs 텐서 연산) ]
        /                                       \
   [ 범용 로직 (Web/DB) ]                 [ 행렬 연산 (AI/HPC) ]
        │                                       │
   4. Host CPU 코어 실행                  5. PCIe/NVLink 거쳐
                                             GPU 텐서 코어 오프로딩
        \                                       /
         +───────────────────+─────────────────+
                             │
                             ▼
   [ 6. 연산 결과 취합 후 SmartNIC을 통해 클라이언트 응답 전송 ]
```

**동작 원리**

1. **패킷 인입**: 400GbE DPU가 패킷을 수신하고 하드웨어 체크섬 검증 및 필터링 수행
2. **NUMA 로컬 적재**: IOMMU를 거쳐 최단 경로 소켓의 로컬 DRAM 버퍼에 DMA 기록
3. **작업 분류**: CPU 스케줄러가 범용 스레드와 행렬 가속 작업을 식별하여 디스패치
4. **연산 실행**: 제어 중심 로직은 CPU 코어가 처리하고 대규모 텐서 연산은 GPU로 오프로드
5. **응답 전송**: 처리된 결과를 SmartNIC으로 직결 전달하여 외부 네트워크로 송출

#### 한줄 요약

- 패킷 유입 $\to$ **NUMA 로컬 메모리 인출 $\to$ 워크로드 분류 $\to$ CPU 범용 / GPU 행렬 가속 $\to$ DPU 응답 반환**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **서버 유형별 비교**:
  - 범용 서버: 2소켓 x86 CPU, 밸런스형 DRAM/I/O, 10~20kW 공랭식
  - AI 가속 서버: 8개 GPU + NVLink 패브릭, 40~100+kW 액체 냉각
  - 스토리지 서버: 대용량 U.2/E1.S NVMe 슬롯 고밀도 집적, 고대역 DPU

</details>

| 비교 항목 | 범용 데이터센터 서버 (General-Purpose) | AI 가속 서버 (GPU / TPU Server) | 스토리지 전용 서버 (Storage-Dense) |
|:---|:---|:---|:---|
| 주력 자원 구성 | 다중 소켓 CPU + 대용량 DDR5 DRAM | 8개 고성능 GPU/NPU + NVLink/NVSwitch | 수십 개 U.2/E1.S NVMe SSD + 고속 DPU |
| 전력 밀도 및 냉각 | 랙당 10~20 kW, 표준 공랭식 팬 냉각 | 랙당 40~100+ kW, 액체 냉각(DLC/침전) | 랙당 15~25 kW, 전후면 공랭식 냉각 |
| 한계 및 위험 | 대규모 행렬 연산 시 처리량 및 전력 한계 | 막대한 전력 소모 및 전용 인프라/냉각 비용 | 연산 능력 부족으로 단순 I/O 서빙에 국한 |

#### 한줄 요약

- 범용 워크로드는 **범용 서버**, LLM/HPC는 **AI 가속 서버**, 데이터 서빙은 **스토리지 서버**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NUMA Pinning**: 프로세스를 특정 NUMA 노드의 CPU 코어 및 메모리에 고정하여 원격 노드 접근 지연을 원천 차단하는 기술.
- **Power Capping(전력 상한 제어)**: 랙 전체 전력 한도를 초과하지 않도록 서버 섀시별 최대 전력 소모를 펌웨어 수준에서 동적으로 강제 제한하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터가 남의 CPU 소켓 메모리에 박혀 있어서 그거 땡겨오느라 대기 타는 **누마**(NUMA) 지연 대참사 발생 | 특정 CPU 코어와 로컬 메모리를 족쇄처럼 묶어버리는 **누마 친화도** 기반 핀(Pinning) 강제 배치 할당 | 남의 소켓 동네까지 건너가는 불필요한 통신 병목을 박멸하고 로컬 대역폭 한계까지 성능 쥐어짜기 달성 |
| SSD와 GPU가 동시에 통신을 시도하다 고속도로인 **피시아이이 루트 포트** 톨게이트가 미어터지는 병목 마비 | 톨게이트 레인을 쪼개는 바이퍼케이션 설정 및 물리적 레인 스위칭 분산 아키텍처 설계 하드웨어 도입 | 터져나가는 입출력 대역폭 톨게이트 병목을 틀어막고 연산기로 가는 텐서 데이터 유입 멈춤 현상 원천 봉쇄 |
| 비싼 가속 칩을 랙에 너무 많이 쑤셔 박아 **랙 전력 밀도** 한도 초과로 차단기가 내려가는 데이터센터 블랙아웃 | 강제로 최고 성능을 깎아 먹는 **전력 상한** 지정 및 차가운 물로 칩을 직접 지져버리는 다이렉트 수랭(D2C) 냉각 도입 | 온도 폭발로 인한 끔찍한 **열 스로틀링** 성능 반 토막을 선제 방어하고 데이터센터 전체 전력 셧다운 참사 원천 방어 |
| 해커가 **베이스보드 관리 컨트롤러**(BMC) 칩에 몰래 기어들어 와 랙의 서버 전원을 몽땅 내려버리는 인프라 암살 위험 | 인터넷망과 물리적으로 랜선을 뽑아버린 대역 외 전용 관리망 격리 및 **펌웨어 서명** 암호 검증 체계 가동 | 해커가 인터넷으로 절대 건드릴 수 없는 무적의 인프라 공급망 보안 및 절대적 물리 셧다운 통제권 방어 체계 확립 |

#### 한줄 요약

- **NUMA Node Pinning·PCIe 분기 최적화·Power Capping & DLC 수랭·BMC 격리/서명 검증**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CXL 메모리 풀링 및 차세대 랙 아키텍처**: CXL 스위치 기반으로 메모리와 GPU를 랙 단위에서 유연하게 할당하는 분해형(Disaggregated) 데이터센터 아키텍처로 진화.

</details>

- 차세대 데이터센터 구축 시 **워크로드 특성에 맞춘 이기종 가속 서버 및 랙 레벨 CXL/액체 냉각 통합 아키텍처 표준 채택**

#### 한줄 요약

- **연산-I/O 균형, 랙 전력 밀도 한도, 장애 범위(Failure Domain)**를 고려한 서버 아키텍처 설계
