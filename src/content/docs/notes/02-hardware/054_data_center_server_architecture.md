## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서버 노드(Server Node)**: CPU, 메모리, 스토리지, 네트워크, 전원 및 관리 모듈을 갖추고 독립 실행되는 데이터센터 기본 단위.
- **장애 도메인(Failure Domain)**: 단일 하드웨어 결함 발생 시 함께 영향을 받을 수 있는 서버, 랙 또는 전원 공급 장치의 물리적 범위.
- **랙(Rack)**: 다수의 서버 노드, ToR 스위치, PDU 및 냉각 팬을 수용하는 표준 데이터센터 실장 캐비닛.

</details>

- 정의/개념: 대규모 클라우드 워크로드에 맞춰 **연산·메모리·스토리지·네트워크**와 전력·냉각·원격 관리를 통합 설계하는 데이터센터 하드웨어 아키텍처
- 배경/필요성: 고밀도 AI 및 클라우드 워크로드 급증에 따른 랙당 전력 밀도 폭증 및 노드 간 I/O 병목 해소 필요

#### 한줄 요약
- 연산, 메모리, 네트워크, 전력, 냉각 및 보안 관리가 최적의 균형을 이루도록 설계된 대규모 인프라의 기본 뼈대다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NUMA(Non-Uniform Memory Access)**: 프로세서와 메모리의 물리적 거리에 따라 접근 지연시간과 대역폭이 달라지는 다중 소켓 아키텍처.
- **OOB(Out-of-Band) 관리**: 메인 OS 및 데이터 네트워크와 완전히 분리된 전용 관리망을 통해 서버를 원격 제어하는 방식.
- **전력 예산(Power Budget)**: 랙 단위 및 서버 섀시 단위로 안전하게 공급하고 냉각할 수 있도록 제한한 최대 소비 전력 한도.

</details>

- 워크로드(웹, DB, AI, 스토리지) 특성에 따른 **자원 비율 최적화 및 모듈화**
- **NUMA 토폴로지 및 PCIe/CXL 인터커넥트** 기반 고대역폭·초저지연 데이터 경로 확보
- **BMC 및 OOB 전용 관리망**을 통한 24/7 원격 모니터링 및 무중단 유지보수 체계

#### 한줄 요약
- 워크로드에 맞춘 자원 비율 구성, NUMA 최적화, OOB 원격 관리를 통해 높은 가용성과 에너지 효율을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **BMC(Baseboard Management Controller)**: 호스트 OS와 독립적으로 동작하여 서버 전원, 센서 모니터링, 펌웨어 업데이트를 수행하는 서비스 프로세서.
- **DPU(Data Processing Unit)**: 네트워크 패킷 처리, 스토리지 가상화, 보안 암호화를 CPU로부터 오프로드하는 프로그래머블 가속기.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 데이터센터 서버 노드 아키텍처                               │
│                                                             │
│  [ 연산 서브시스템 ]         [ 가속 서브시스템 ]             │
│  ├─ Multi-Socket CPU         ├─ GPU / NPU 가속기 클러스터    │
│  └─────────────┬─────────────┴─────────────┬─────────────┘  │
│                │ (UPI / Infinity Fabric)   │ (PCIe / CXL)   │
│  [ 메모리 서브시스템 ]       [ 스토리지 서브시스템 ]         │
│  ├─ DDR5 / CXL 메모리 풀     ├─ NVMe SSD / E1.S / E3.S      │
│  └─────────────┬─────────────┴─────────────┬─────────────┘  │
│                │                           │                │
│  [ I/O 및 통신 서브시스템 ]                                │
│  ├─ DPU / SmartNIC (RDMA / RoCE / InfiniBand)               │
│  └─────────────┬─────────────────────────────────────────┘  │
│                │                                            │
│  [ 인프라 및 관리 계층 ]                                    │
│  ├─ 이중화 전원 공급기 (CRPS) / 직접 액체 냉각(DLC) 루프     │
│  └─ BMC (Baseboard Management Controller / OpenBMC)         │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 고속 인터커넥트를 통해 연산, 메모리, 가속기, 스토리지 및 DPU가 초고속 데이터망으로 결합

| 구성요소 | 책임 |
|:---|:---|
| CPU 및 가속기 | 범용 제어 로직 실행 및 대규모 병렬 AI/HPC 워크로드 전담 연산 |
| 메모리/스토리지 | 고속 DDR5 DRAM, CXL 확장 메모리 및 초고속 NVMe 플래시 I/O 제공 |
| DPU / SmartNIC | OVS 가상 스위칭, NVMe-oF 스토리지 오프로드 및 제로 트러스트 보안 격리 |
| 전력/냉각 인프라 | 고효율 Titanium급 파워 서플라이(PSU) 및 랙 레벨 수랭식 직접 냉각(DLC) |
| BMC / OpenBMC | 전원 원격 제어, 하드웨어 텔레메트리 수집, Redfish API 기반 오케스트레이션 |

#### 한줄 요약
- 연산, 메모리, DPU 네트워크, 고효율 전원/냉각, BMC 관리 모듈이 표준 섀시 내에 밀결합되어 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **코어 친화도(Core Affinity)**: 특정 프로세스나 인터럽트 핸들러를 물리적으로 가장 가까운 NUMA 노드의 CPU 코어에 고정 실행하는 기법.

</details>

```text
클라이언트 요청 인입 (ToR 스위치)
      │
      ▼
1. DPU/SmartNIC: 네트워크 패킷 수신, 방화벽 검사 및 호스트 DMA 버퍼 전송
      │
      ▼
2. OS 스케줄러: NUMA 토폴로지 및 코어 친화도 기반 최적 코어로 태스크 할당
      │
      ▼
3. CPU 및 가속기: 온칩 캐시 및 CXL 메모리 풀 참조하여 고속 비즈니스 연산
      │
      ▼
4. 스토리지 I/O: NVMe-oF 및 로컬 SSD 직접 쓰기/읽기 수행
      │
      ▼
5. BMC 텔레메트리: 소비 전력, 섀시 온도, 팬 속도 실시간 측정 및 클라우드 보고
```

**동작 원리**

1. **패킷 유입 및 DPU 가속**: 네트워크 패킷을 DPU가 수신하여 보안 룰을 처리한 뒤 제로 카피로 메모리에 적재
2. **NUMA 최적 스케줄링**: 프로세스를 로컬 메모리와 직결된 CPU 코어에 할당하여 원격 메모리 지연 제거
3. **가속 연산 수행**: CPU와 GPU/NPU가 PCIe Gen5/CXL 고속 버스를 통해 데이터를 교환하며 연산 완료
4. **I/O 및 응답 반환**: 연산 결과를 고속 네트워크를 통해 송출하고 스토리지에 트랜잭션 기록
5. **인프라 관측**: BMC가 지속적으로 전력 및 온도 센서를 폴링하여 전력 캡(Power Capping) 및 쿨링 제어

#### 한줄 요약
- 패킷 유입 → DPU 오프로드 → NUMA 기반 연산 → I/O 저장 → BMC 텔레메트리 모니터링 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 서버 아키텍처 유형 | 범용 연산 서버 | AI 가속 서버 | 고밀도 스토리지 서버 | 엣지 마이크로 서버 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 웹, WAS, DB, 일반 가상화 | 거대 LLM 학습 및 딥러닝 추론 | 빅데이터 레이크, 분산 파일 시스템 | 5G 기지국, 스마트 팩토리 현장 |
| 핵심 특징 | 다중 코어 CPU와 대용량 DRAM 균형 | 8-GPU 풀메시 NVLink 및 액체 냉각 | 다수의 NVMe/SATA 핫스왑 드라이브 베이 | 소형 폼팩터, 내환경성 및 저전력 |
| 주요 제약 | GPU 텐서 연산 가속 불가 | 극심한 소비 전력(수십 kW/랙) 및 발열 | CPU 연산 파워 및 네트워크 대역폭 제한 | 확장성 제한 및 부품 업그레이드 제약 |

#### 한줄 요약
- 범용은 균형 서버, AI는 GPU 가속 서버, 데이터 저장은 스토리지 서버, 현장 배포는 엣지 서버를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **파워 캐핑(Power Capping)**: 랙 전체 전력 공급 한도를 초과하지 않도록 서버 코어 클록을 동적으로 제한하는 전력 통제 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소켓 간 원격 메모리 접근으로 인한 **NUMA 지연시간 급증** | NUMA 노드별 로컬 메모리 바인딩 및 **코어 친화도(Affinity)** 설정 | 메모리 지연시간 단축 및 처리율 30% 이상 향상 |
| 고밀도 가속기 랙의 **전력 밀도 폭증 및 국소 과열** | **직접 액체 냉각(Direct Liquid Cooling)** 및 동적 **파워 캐핑** 적용 | PUE 개선 및 열 스로틀링 방지 |
| 패킷 처리 및 암호화 부하로 인한 **호스트 CPU 연산력 낭비** | **DPU/SmartNIC** 기반 인프라 서비스 오프로딩 구현 | 순수 비즈니스 로직용 CPU 코어 100% 확보 |
| 악의적 접근으로 인한 **BMC 및 펌웨어 침해 위협** | **하드웨어 RoT(Root of Trust)** 및 펌웨어 암호학적 서명 검증 | 공급망 공격 방어 및 신뢰 부팅(Secure Boot) 보장 |

#### 한줄 요약
- NUMA 바인딩으로 메모리 지연을 줄이고, 액체 냉각과 파워 캐핑으로 전력/열을 통제하며, DPU로 CPU를 해방한다.

## Ⅶ. 결론

- 대규모 데이터센터 인프라는 워크로드에 최적화된 **이기종 가속기·DPU·액체 냉각 통합 서버 아키텍처** 구축 필수

#### 한줄 요약
- 연산 밀도, 고대역폭 인터커넥트, 고효율 냉각 및 하드웨어 보안을 종합 연계하여 지속 가능한 데이터센터 인프라를 실현해야 한다.
