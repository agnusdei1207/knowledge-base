## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터커넥트 토폴로지(Interconnect Topology)**: 수천~수만 개의 GPU, 가속기, 스토리지 노드를 상호 연결하는 물리적 배선 배치 및 논리적 라우팅 그래프 구조.
- **양분 대역폭(Bisection Bandwidth)**: 네트워크를 두 개의 동일한 크기로 양분했을 때 두 영역 사이를 통과할 수 있는 최소 총 전송 대역폭.

</details>

- 정의/개념: AI/HPC 클러스터에서 상위 대역폭을 비례 확장하는 **무차단 팻트리(Fat-Tree)** 와 $n$차원 격자 끝단을 순환 연결하는 **토러스(Torus)** 네트워크 토폴로지
- 배경/필요성: 대규모 분산 학습 시 All-Reduce 통신 병목 극복 및 케이블 배선 비용과 망 지름 최적화 필요

#### 한줄 요약
- 전체 노드가 막힘없이 1:1 전송하는 팻트리(NVIDIA SuperPOD)와 인접 노드끼리 격자로 묶어 비용을 아끼는 토러스(Google TPU) 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **무차단 네트워크(Non-blocking Network)**: 모든 노드가 임의의 목적지로 동시에 최고 속도로 데이터를 전송해도 대역폭 병목이나 정체가 발생하지 않는 구조.
- **망 지름(Network Diameter)**: 네트워크 내 임의의 두 노드 간 최단 경로 중 가장 긴 홉(Hop) 수로 최악 전송 지연시간을 결정하는 척도.

</details>

- **팻트리 (Fat-Tree)**: 상위 계층으로 갈수록 링크를 증설하여 1:1 완전 **양분 대역폭(Full Bisection Bandwidth)** 보장
- **토러스 (Torus)**: 각 노드가 주변 인접 노드와 연결되고 **랩어라운드(Wraparound) 순환 링크**로 망 지름 축소
- 트래픽 부하 분산(ECMP) 및 순환 링 교착상태 방지를 위한 **가상 채널(Virtual Channel)** 지원

#### 한줄 요약
- 팻트리는 스위치를 대량 투입해 무차단 대역폭을 뚫어주고, 토러스는 링 격자 구조로 스위치 비용을 극소화한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스파인-리프(Spine-Leaf)**: 서버가 연결되는 리프(Leaf) 스위치와 리프들을 상호 결합하는 스파인(Spine) 스위치로 구성된 2/3단계 Clos 네트워크.
- **랩어라운드 링크(Wraparound Link)**: 토러스 격자 끝단의 경계 노드를 반대편 끝단 노드와 직접 링 형태로 연결하는 케이블.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ 팻트리(Clos Network) vs 3D 토러스(Torus) 아키텍처 비교      │
│                                                             │
│  [ 1. 팻트리 (Fat-Tree / Spine-Leaf) ]                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 스파인 백본 스위치 계층 (Spine Switch 1, 2, 3, 4)     │  │
│  └───────────┬───────────────┬───────────────┬───────────┘  │
│              │ (Non-blocking)│               │              │
│  ┌───────────▼───────────────▼───────────────▼───────────┐  │
│  │ 리프/ToR 스위치 계층 (Leaf Switch 1, 2, 3, 4)         │  │
│  └───────────┬───────────────┬───────────────┬───────────┘  │
│              │               │               │              │
│  [ GPU 서버 1 ]         [ GPU 서버 2 ]  [ GPU 서버 3 ]      │
│                                                             │
│  [ 2. 3D 토러스 (3D Torus / Point-to-Point Mesh) ]          │
│       ┌─────────┐         ┌─────────┐                       │
│       │ 노드(X) ├─────────┤노드(X+1)│                       │
│       └───┬─────┘         └────┬────┘                       │
│           │                    │                            │
│       ┌───┴─────┐         ┌────┴────┐                       │
│       │ 노드(Y) ├─────────┤노드(Y+1)│                       │
│       └───┬─────┘         └────┬────┘                       │
│           └─ (Wraparound 순환 링 결합) ─┘                   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 팻트리는 Spine-Leaf 스위치를 통해 1:1 무차단 통신을 지원하며, 토러스는 노드 간 점대점 격자 및 랩어라운드 링으로 연결

| 구성요소 | 책임 |
|:---|:---|
| 리프 스위치 (Leaf/ToR) | 서버 랙 내부의 GPU 노드들을 집선하고 상위 스파인 스위치로 트래픽을 ECMP 분산 |
| 스파인 스위치 (Spine) | 리프 스위치 간의 글로벌 크로스바 백본 교환을 전담하여 무차단 양분 대역폭 보장 |
| 토러스 라우터 (Router) | 각 가속기 노드에 직결되어 6개 방향($\pm X, \pm Y, \pm Z$)으로 패킷을 홉 바이 홉 전송 |
| 랩어라운드 링크 | 격자의 양 끝단을 순환 연결하여 최장 홉 거리를 절반으로 단축시키는 고속 케이블 |
| 패킷 스케줄러 (ECMP) | 동일 비용 다중 경로로 트래픽을 플로우 해시 기반 분산시켜 네트워크 핫스팟 제거 |

#### 한줄 요약
- 리프/스파인 스위치(팻트리), 점대점 라우터와 랩어라운드 링크(토러스)가 2대 인터커넥트를 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **차원 순서 라우팅(DOR, Dimension Order Routing)**: $X \to Y \to Z$ 축 순서대로 차원을 하나씩 일치시켜 나가며 패킷을 전달하여 데드락을 방지하는 알고리즘.

</details>

```text
분산 딥러닝 텐서 전송 요청 (All-Reduce / P2P)
      │
      ├──────────────────────────────┬──────────────────────────────┐
      ▼                              ▼                              ▼
[ 팻트리 (Fat-Tree) 경로 ]             [ 토러스 (Torus) 경로 ]
1. 출발지 Leaf 가 ECMP 해시로          1. 차원 순서 라우팅(DOR: $X \to Y \to Z$)
   다중 Spine 중 최적 업링크 선택         인접 이웃 노드로 홉 바이 홉 전송
      │                              │
      ▼                              ▼
2. Spine 스위치 백본 직결 스위칭     2. 랩어라운드(Wraparound) 링크 경유
   (Non-blocking 1:1 대역폭)            격자 반대편 최단 홉 즉시 점프
      │                              │
      ▼                              ▼
3. 목적지 Leaf 거쳐 타깃 GPU 도착     3. 목적지 좌표 도달 시 가속기 인입
      │                              │
      └──────────────────────────────┴──────────────────────────────┘
                                     ▼
                      최종 패킷 수신 및 집단 통신 완료
```

**동작 원리**

1. **토폴로지 분기**: 시스템 아키텍처에 따라 팻트리 스파인 라우팅 또는 토러스 차원 라우팅 선택
2. **팻트리 전송**: Leaf 스위치가 ECMP 알고리즘으로 Spine에 분산 전달 후 단 2~3홉 만에 목적지 도달
3. **토러스 전송**: $X \to Y \to Z$ 좌표 순서대로 인접 노드를 거치며 이동하고 경계 도달 시 랩어라운드 점프
4. **혼잡 제어**: 팻트리는 적응형 라우팅으로 우회하고, 토러스는 가상 채널(VC)로 버퍼 교착상태 해소
5. **통신 완료**: 타깃 가속기 레지스터로 패킷이 인입되며 All-Reduce 텐서 동기화 완료

#### 한줄 요약
- 팻트리는 Spine 업/다운 3홉 전달, 토러스는 $X \to Y \to Z$ 인접 홉 이동 및 랩어라운드 점프로 완결된다.

## Ⅴ. 종류 및 비교

| 인터커넥트 토폴로지 | 팻트리 (Fat-Tree / Clos) | 3D/6D 토러스 (Torus) | 드래곤플라이 (Dragonfly) | 하이퍼큐브 (Hypercube) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초거대 LLM 학습(All-to-All 통신) | 텐서 병렬화 및 TPU 가속기 클러스터 | 초대규모 슈퍼컴퓨터(HPC) | 중소형 병렬 시스템 및 온칩 네트워크 |
| 핵심 특징 | 완전 무차단 1:1 양분 대역폭 보장 | 스위치 없이 노드 직결 및 인접 저지연 | 고밀도 로컬 그룹 + 장거리 글로벌 광 링크 | $n$차원 큐브 정점 연결(지름 $\log_2 N$) |
| 한계 | 방대한 스위치 수량 및 케이블 비용 급증 | 홉 수 증가 시 지연 누적 및 데드락 방지 필수 | 글로벌 링크 라우팅 및 부하 분산 복잡도 | 노드당 포트 수가 $\log_2 N$으로 증가해 확장 한계 |

#### 한줄 요약
- 범용 AI 클러스터는 팻트리, TPU 전용망은 토러스, 초대규모 슈퍼컴은 드래곤플라이를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **초과 가입(Oversubscription)**: 상위 스파인 계층의 총 대역폭을 하위 리프 계층의 대역폭보다 작게 설계(예: 2:1)하여 스위치 구축 비용을 절감하는 트레이드오프 설계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토러스 순환 구조에서 패킷들이 꼬리를 물고 무한 대기하는 **라우팅 데드락(Deadlock)** | **가상 채널(Virtual Channel)** 분할 및 **DOR(차원 순서 라우팅)** 강제 | 버퍼 순환 종속성 원천 차단 |
| 수만 GPU 팻트리 구축 시 **천문학적인 스파인 스위치 및 광케이블 비용 폭증** | 상위 계층에 **제한적 초과 가입(Oversubscription 2:1)** 및 광회선 스위치(OCS) 적용 | 네트워크 구축 TCO 40% 이상 절감 |
| All-Reduce 집단 통신 시 특정 스파인 링크로 트래픽이 몰리는 **핫스팟(Hotspot) 체증** | **적응형 라우팅(Adaptive Routing)** 및 **인시던트 텔레메트리(INT)** 연동 | 실시간 유휴 링크 우회 및 부하 균등화 |
| 대규모 클러스터 패킷 손실로 인한 **RDMA 재전송 및 지연시간 급증(PFC Deadlock)** | **ECN 기반 DCQCN 혼잡 제어** 및 가상 레인 버퍼 격리 | 무손실(Lossless) 초저지연 RoCEv2 전송 보장 |

#### 한줄 요약
- 가상 채널로 토러스 데드락을 풀고, 초과 가입/OCS로 팻트리 비용을 아끼며, DCQCN으로 RDMA 체증을 막는다.

## Ⅶ. 결론

- 대규모 LLM All-Reduce 가속 인프라는 **NVIDIA InfiniBand 기반 팻트리(Fat-Tree)**, 텐서 국소 집적 인프라는 **Google TPU 기반 3D Torus**를 워크로드별 최적 채택

#### 한줄 요약
- 분산 연산의 통신 패턴(Collective vs Local Stencil)과 양분 대역폭, 구축 비용을 종합 고려하여 최적의 인터커넥트 토폴로지를 설계해야 한다.
