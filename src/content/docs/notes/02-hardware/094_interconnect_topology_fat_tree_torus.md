## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Interconnect Topology(인터커넥트 토폴로지)**: 수천~수만 개의 연산 노드, 스위치, 메모리 간의 물리적 배선 연결 방식 및 논리적 데이터 라우팅 그래프 구조.
- **Fat-Tree(팻트리)**: 전통적인 트리의 상위 계층 병목을 없애기 위해 루트(스파인) 방향으로 갈수록 링크 대역폭을 비례 확장하여 완전 무차단(Full Bisection Bandwidth)을 제공하는 Clos 네트워크.
- **Torus(토러스)**: 2D/3D/6D 그리드(Grid) 격자의 양 끝단 노드를 원환체(Torus/Ring) 형태로 순환 연결하여 망 지름을 반감시킨 토폴로지.

</details>

- 정의/개념: 수천~수만 개의 GPU, 가속기, 스토리지 및 연산 노드를 고속으로 연결하는 대규모 AI/HPC 클러스터 네트워크에서, 트리 상위 계층으로 갈수록 대역폭을 비례 확장하여 무차단(Non-blocking)을 보장하는 팻트리(Fat-Tree)와, $n$차원 그리드 양 끝단을 링 형태로 연결하여 인접 노드 간 통신을 극대화하는 토러스(Torus)의 인터커넥트 토폴로지 설계 체계
- 배경/필요성: 대규모 분산 딥러닝 학습(All-Reduce, All-to-All) 및 과학 시뮬레이션의 **통신 패턴, 양분 대역폭(Bisection Bandwidth), 망 지름(Network Diameter) 및 케이블 비용 간의 트레이드오프 최적화 필수**

#### 한줄 요약

- 대규모 분산 클러스터를 위한 **무차단 전결합 팻트리(Fat-Tree)와 국소 인접 고밀도 토러스(Torus) 토폴로지**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Bisection Bandwidth(양분 대역폭)**: 네트워크를 임의의 동일한 크기 두 부분으로 분할했을 때 양쪽 사이를 통과할 수 있는 최소 총 전송 대역폭.
- **Network Diameter(망 지름)**: 임의의 두 노드 간 최단 경로 중 가장 긴 홉(Hop) 수로 최악 지연시간(Worst-case Latency) 척도.
- **ECMP(Equal-Cost Multi-Path)**: 동일한 거리의 복수 경로로 트래픽을 플로우 해시 기반으로 균등 분산하는 라우팅 기법.

</details>

- 상위 계층으로 갈수록 스위치 포트 수를 대칭 확장하여 1:1 완전 **양분 대역폭(Full Bisection Bandwidth)** 보장 (팻트리)
- 각 노드가 주변 $2d$개의 이웃 노드와 직접 연결되고 **랩어라운드(Wraparound) 링크**를 통해 망 지름을 축소 (토러스)
- 트래픽 편중을 방지하고 경로 가용성을 극대화하는 **ECMP 및 적응형 다중 경로 라우팅(Adaptive Routing)**

#### 한줄 요약

- **1:1 완전 양분 대역폭(Fat-Tree)·랩어라운드(Wraparound) 링 연결(Torus)·ECMP 및 적응형 다중 경로 라우팅**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Spine/Core Switch**: 팻트리 최상단에서 리프 스위치들 간의 글로벌 패킷 스위칭을 담당하는 고성능 백본 스위치.
- **Leaf/ToR Switch**: 랙 내부의 연산 서버들을 직접 집선하고 상위 스파인 스위치들로 업링크를 분산하는 스위치.
- **Wraparound Link**: 토러스 격자 끝단(Boundary) 노드들을 반대편 끝단 노드와 물리적으로 링 결합하는 순환 케이블.

</details>

```text
[ 팻트리(Clos Network) vs 3D 토러스(Torus) 아키텍처 비교 ]
 
 [ 1. 팻트리 (Fat-Tree) ]               [ 2. 3D 토러스 (3D Torus) ]
┌──────────────────────────────┐       ┌──────────────────────────────┐
│ Spine 1 │ Spine 2 │ Spine 3  │       │ Node(x,y,z) ── Node(x+1,y,z) │
├──────────────────────────────┤       │      │                │      │
│ Leaf 1  │ Leaf 2  │ Leaf 3   │       │ Node(x,y+1) ── Node(x+1,y+1) │
├──────────────────────────────┤       ├──────────────────────────────┤
│ Server 1│ Server 2│ Server 3 │       │ 랩어라운드 링 순환 케이블 결합│
└──────────────────────────────┘       └──────────────────────────────┘
```

선의 의미: 팻트리(Spine-Leaf 스위치 계층) vs 토러스(3D/6D 메시 랩어라운드 라우터) 인터커넥트 토폴로지 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 리프 스위치 | 서버 랙 밑바닥에 딱 붙어서 서버들이 던지는 패킷을 받아먹고 위로(**ECMP**) 골고루 뿌려주는 1차 수집가 |
| 스파인 스위치 | 네트워크 꼭대기에 앉아서 리프 스위치들이 던지는 무지막지한 트래픽을 감당하는 괴물 백본 |
| 토러스 라우터 | 상하좌우(3D/6D)로 연결된 좌표망에서 "목적지가 어디냐" 묻고 가장 빠른 이웃집으로 패킷을 토스하는 교환기 |
| 랩어라운드 링크 | 맵 끝에서 끝을 둥글게 이어버려, 저 멀리 반대편으로 갈 때 중앙을 거치지 않게 해주는 웜홀 케이블 |

#### 한줄 요약

- **리프 스위치(Leaf/ToR)·스파인/코어 스위치(Spine)·토러스 라우터(Router)·랩어라운드 링크(Wraparound Link)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Adaptive Routing(적응형 라우팅)**: 패킷 전송 시 혼잡(Congestion) 상태의 기본 경로를 회피하여 실시간 유휴 링크로 자동 우회하는 라우팅 메커니즘.

</details>

```text
[ 인터커넥트 토폴로지별 패킷 라우팅 흐름 ]
                         │
        +────────────────┴────────────────────────+
        │             [ 토폴로지 구조 판정 ]      │
        │             /                         \ │
        │     [ 팻트리 (Fat-Tree) ]           [ 토러스 (Torus) ]
        │            │                                │
        │ 1. ECMP 해싱으로 상위 Leaf ──>  3. $X \to Y \to Z$ 차원 순서
        │    Spine 스위치로 업링크 분산       (DOR) 기반 이웃 노드 전송
        │            │                                │
        │ 2. Spine 이 목적지 Leaf 스위치  4. 경계 도달 시 Wraparound 링크
        │    디코딩 후 다운링크 직결          경유 최단 홉(Hop) 전달
        +────────────────┬────────────────────────+
                         │
                         ▼
   [ 5. 타깃 가속기/서버 엔드포인트 패킷 도착 및 트랜잭션 종결 ]
```

**동작 원리**

1. **팻트리 상향 전달**: 출발지 서버가 보낸 패킷을 Leaf 스위치가 ECMP 해시 알고리즘을 통해 다중 Spine 링크 중 하나로 포워딩
2. **팻트리 하향 직결**: Spine 스위치가 패킷의 최종 IP/LID를 확인하고 타깃 Leaf 스위치로 다운링크 전송
3. **토러스 차원 순서 라우팅**: $X$축, $Y$축, $Z$축 순서로 인접 라우터를 거치며 목적지 좌표를 향해 홉 바이 홉(Hop-by-hop) 이동
4. **랩어라운드 횡단**: 좌표 차이가 절반을 초과할 경우 랩어라운드 링크를 통해 격자 반대편으로 즉시 점프하여 지연 단축

#### 한줄 요약

- 통신 패턴 분석 $\to$ **팻트리 경로(ECMP 상향 Spine 전달 $\to$ 하향 Leaf 목적지 직결) vs 토러스 경로(차원 순서 라우팅 $\to$ 랩어라운드 홉 전달) $\to$ 패킷 도착 완료**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Fat-Tree vs Torus vs Dragonfly**:
  - Fat-Tree: 완전 무차단 양분 대역폭, 짧은 망 지름, 대규모 All-to-All 특화, 높은 스위치/케이블 비용
  - Torus: 인접 통신(Stencil/TPU) 최적화, 스위치 비용 저렴, 홉 수 증가 시 지연시간 누적
  - Dragonfly: 그룹 내 고밀도 메시 + 그룹 간 글로벌 광 링크 결합, 초대규모 슈퍼컴퓨터(HPC)

</details>

| 비교 항목 | 팻트리 (Fat-Tree / Clos Network) | 3D/6D 토러스 (Torus Topology) | 드래곤플라이 (Dragonfly Topology) |
|:---|:---|:---|:---|
| 구조 및 양분 대역폭 | 다계층 스위치 트리, 100% 무차단 양분 대역폭 보장 | $n$차원 격자 끝단 순환 연결, 직경 $O(N^{1/d})$ | 고밀도 그룹 내 전결합 + 그룹 간 글로벌 광 링크 |
| 최적 적합 통신 패턴 | 무작위 전송 및 대규모 All-to-All / All-Reduce | 국소 인접(Stencil) 및 규칙적 텐서 병렬 통신 | 장거리 글로벌 통신 및 초거대 슈퍼컴퓨팅 |
| 한계 및 비용 특성 | 스위치 수 및 광케이블 비용 급증 (고비용) | 홉 수 증가 시 지연시간 증가, 데드락 방지 필요 | 글로벌 링크 라우팅 알고리즘 복잡도 높음 |

#### 한줄 요약

- AI All-Reduce는 **팻트리(Fat-Tree)**, 텐서 국소 연산은 **토러스(Torus)**, 초대규모 슈퍼컴은 **드래곤플라이**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Routing Deadlock(라우팅 교착 상태)**: 토러스와 같은 순환 링 토폴로지에서 패킷 버퍼가 순환 의존성을 형성하여 네트워크 전체가 영구 동결되는 현상.
- **Virtual Channel(가상 채널)**: 단일 물리 링크를 논리적으로 복수의 독립된 버퍼 큐로 분할하여 데드락 순환 고리를 끊는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토러스 구조에서 트래픽이 둥글게 꼬리를 물고 무한 대기하는 최악의 **교착 상태(Deadlock)** 발생 | 가상 채널(Virtual Channel)을 뚫어서 패킷이 막히면 갓길로 돌려버리는 순서화 라우팅 적용 | 꼬리물기로 네트워크 전체가 뻗어버리는 재앙을 원천 차단하고 순환 뚫어냄 |
| 팻트리 만들려다 꼭대기 비싼 스위치와 광케이블 값이 천문학적으로 치솟아서 파산 위기 | 윗선 대역폭을 일부러 살짝 줄이는 **초과 가입(Oversubscription)** 꼼수 타협 | 안 쓰는 트래픽 마진을 쳐내서 수백억 원짜리 구축 단가 방어 |
| GPU 수만 대가 한 번에 **올-리듀스** 때리다가 특정 스위치(핫스팟)가 불타 터지기 직전 발발 | 스위치가 막히면 덜 막히는 길로 알아서 피해 가는 **적응형 라우팅** 강제 발동 | 패킷을 이리저리 찢고 분산시켜서 핫스팟 폭주를 씹어먹음 |

#### 한줄 요약

- **가상 채널(Virtual Channel) 및 DOR 기반 토러스 데드락 방지·Top 계층 초과 구독(Oversubscription) 비용 절감·적응형 라우팅(Adaptive Routing) 핫스팟 해소**
