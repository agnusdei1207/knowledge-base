## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인터커넥트 토폴로지(Interconnect Topology)**: 수만 대의 AI 서버나 슈퍼컴퓨터가 서로 데이터를 던질 때, 병목 없이 빛의 속도로 꽂아주기 위해 네트워크 선을 깔아놓는 거미줄 맵핑 설계도이다.
- **팻트리(Fat-Tree)**: 위로 갈수록 나뭇가지가 굵어지는 구조로, 데이터가 몰리는 중앙 고속도로 차선을 무식하게 늘려서 100% 병목을 씹어먹는 부르주아형 네트워크이다.
- **토러스(Torus)**: 서버들을 큐브처럼 연결하고, 지도 끝에서 끝을 둥글게 이어 붙여서 반대편까지 웜홀로 한 방에 넘어가게 만드는 도넛 모양 네트워크이다.

</details>

- 정의: 수만 대의 AI 서버나 슈퍼컴퓨터가 서로 데이터를 던질 때, 병목 없이 빛의 속도로 꽂아주기 위해 네트워크 선을 깔아놓는 물리적/논리적 거미줄 구조인 **인터커넥트 토폴로지**
- 배경: 서버가 수천 대로 늘어나면, 아무리 개별 성능이 좋아도 선 연결 방식이 구리면 윗선 통신망이 막혀서(병목) 전체 기계가 다 같이 뻗어버리기 때문

#### 한줄 요약

- 수만 대의 컴퓨터가 싸우지 않고 데이터를 주고받도록 길(토폴로지)을 어떻게 뚫어줄 건지 결정하는 설계도이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **양분 대역폭(Bisection Bandwidth)**: 수만 대의 서버를 칼로 반 토막 냈을 때, 왼쪽 팀과 오른쪽 팀이 서로 주고받을 수 있는 최대 통신 속도로, 네트워크 방어력의 핵심 스펙이다.
- **망 지름(Network Diameter)**: 제일 멀리 있는 놈한테 데이터를 보낼 때 스위치를 최대 몇 번이나 거쳐야 하는지 따지는 '최악의 뺑뺑이 횟수'이다.
- **동등 비용 다중 경로(Equal-Cost Multi-Path, ECMP)**: 한 길만 고집하다 막혀서 터지지 않게, 똑같은 거리의 길 여러 개에 패킷을 찢어서 골고루 쏴버리는 교통정리 꼼수이다.

</details>

- 루트(중심)로 갈수록 고속도로 차선을 무식하게 늘려서, 전체 네트워크를 반으로 쪼개도 데이터가 펑펑 쏟아지는 **양분 대역폭**을 사수함(팻트리).
- 좌우상하 끝에 있는 노드들을 동그랗게 다시 말아서 연결해 버려, 지구 반대편 데이터도 바로 옆에서 뽑아 쓰는 **토러스** 구조를 씀.
- 트래픽이 한쪽으로 몰려 폭발하지 않게 여러 갈래 길로 데이터를 분산시키는 **동등 비용 다중 경로(ECMP)** 꼼수를 시전함.

#### 한줄 요약

- 팻트리는 차선을 넓혀 병목을 부수고(양분 대역폭), 토러스는 끝과 끝을 이어 웜홀을 파며, ECMP로 차를 골고루 분산시킨다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스파인/코어 스위치(Spine/Core Switch)**: 네트워크 꼭대기에서 모든 데이터를 내려다보며, 밑에서 던지는 무지막지한 트래픽을 혼자 다 받아내는 괴물 백본 스위치이다.
- **리프 스위치(Leaf/Access Switch)**: 서버 랙 제일 밑바닥에 딱 붙어서 서버들이 던지는 패킷을 1차로 싹 쓸어 담아 위로 올려보내는 수집가이다.
- **랩어라운드 링크(Wraparound Link)**: 토러스 구조에서 맵 끝에 다다른 패킷을 반대편 끝으로 순간이동 시켜주는 마법의 웜홀 케이블이다.

</details>

```text
[ 인터커넥트 토폴로지 십자포화 아키텍처 ]
      ( 돈 바른 팻트리 길 )                  ( 둥글게 만 토러스 길 )
      [ 스파인 스위치 (보스) ]                       [ 토러스 라우터 ]
         │         │                               │        │
  [ 리프 스위치 ] [ 리프 스위치 ]                    [ 이웃 노드 토스 ]
         │         │                               │        │
      [ 연산 노드 (하위 서버) ]                     [ 랩어라운드 링크 (웜홀) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **리프 스위치** | 서버 랙 밑바닥에 딱 붙어서 서버들이 던지는 패킷을 받아먹고 위로(**ECMP**) 골고루 뿌려주는 1차 수집가 |
| **스파인 스위치** | 네트워크 꼭대기에 앉아서 리프 스위치들이 던지는 무지막지한 트래픽을 감당하는 괴물 백본 |
| 토러스 라우터 | 상하좌우(3D/6D)로 연결된 좌표망에서 "목적지가 어디냐" 묻고 가장 빠른 이웃집으로 패킷을 토스하는 교환기 |
| **랩어라운드 링크** | 맵 끝에서 끝을 둥글게 이어버려, 저 멀리 반대편으로 갈 때 중앙을 거치지 않게 해주는 웜홀 케이블 |

#### 한줄 요약

- 팻트리는 밑(리프)에서 모아 위(스파인)로 쏘고, 토러스는 옆집으로 넘기다 웜홀(랩어라운드)을 탄다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **적응형 라우팅(Adaptive Routing)**: 원래 가려던 길이 막혀 있으면 "어? 막혔네?" 하고 바로 옆 갓길로 눈치껏 우회해서 꽂아버리는 스마트 내비게이션 기능이다.

</details>

```text
[ 인터커넥트 십자포화 라우팅 패킷 전송 흐름 ]
                                 │
                 ┌───────────────┴───────────────┐
            ( 팻트리: 위아래로 )              ( 토러스: 옆으로 둥글게 )
                 ▼                               ▼
[ 1. 상향 쏴올리기: 덜 막히는 길(ECMP)로 ] [ 3. 웜홀 타기: 출발 노드가 좌표 찍고 ]
[ 리프에서 스파인으로 패킷 냅다 던짐 ]      [ 옆집 라우터로 패킷 핑퐁 시작함 ]
                 │                               │
                 ▼                               ▼
[ 2. 하향 내리꽂기: 스파인이 목적지 ]      [ 4. 순환 뺑뺑이: 랩어라운드 링크 타며 ]
[ 리프 찾아서 아래로 냅다 꽂아버림 ]        [ 목적지 나올 때까지 계속 옆으로 넘김 ]
```

### 동작 원리

1. 상향 쏴올리기(팻트리): 출발 노드가 리프 스위치에 패킷을 던지면, 덜 막히는 길(**ECMP**)을 찾아 최상위 스파인 스위치로 쏴버림.
2. 하향 내리꽂기(팻트리): 스파인 스위치가 목적지 리프 스위치를 찾아내서 냅다 패킷을 내리꽂음.
3. 웜홀 타기(토러스): 토러스 구조에서는 출발 노드가 좌표를 찍고 옆집 라우터로 패킷을 계속 토스함.
4. 순환 뺑뺑이(토러스): **랩어라운드 링크**를 타면서 목적지 좌표가 나올 때까지 이웃집으로 핑퐁을 침.

#### 한줄 요약

- 팻트리는 위로 쐈다가 아래로 꽂고, 토러스는 목적지 좌표 맞을 때까지 웜홀 타며 옆으로 계속 패스한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **올-리듀스(All-Reduce)**: AI 학습할 때, GPU 만 대가 각자 푼 정답을 한 번에 다 모아서 합치고 다시 똑같이 나눠 갖는 무자비한 집단 통신 패턴이다.

</details>

| 비교 항목 | **팻트리** (Fat-Tree Topology) | **토러스** (3D / 6D Torus Topology) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 엔비디아 GPU 수만 대가 한 번에 데이터를 쏟아내며(**올-리듀스**) 무식하게 합칠 때 | 구글 TPU처럼 옆집 데이터만 계속 긁어오면(스텐실) 계산이 끝나는 딥러닝 환경일 때 |
| 아키텍처 핵심 구현 특징 | 위로 갈수록 스위치를 무식하게 늘려서 **양분 대역폭** 병목을 100% 씹어먹는 나무 구조 | 노드들을 바둑판처럼 엮고 끝과 끝을 둥글게 말아서, 웜홀(**랩어라운드**)을 만들어버린 입체 구조 |
| 극복해야 할 태생적 한계점 | 꼭대기(스파인)로 갈수록 비싼 스위치랑 케이블이 미친 듯이 필요해서 돈이 썩어남 | 데이터가 멀리 갈수록 중간에 거치는 라우터(홉)가 많아져서 속도가 굼벵이처럼 느려짐 |

#### 한줄 요약

- 팻트리는 비싸지만 다 같이 섞일 때 최고고, 토러스는 멀리 갈 땐 느려도 옆집이랑 놀 땐 싸고 빠르다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **교착 상태(Deadlock)**: 패킷 4개가 서로 "네가 먼저 가!" 하면서 사거리를 꽉 막고 시스템 전체를 다운시켜 버리는 끔찍한 네트워크 꼬리물기 참사이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토러스 구조에서 트래픽이 둥글게 꼬리를 물고 무한 대기하는 최악의 **교착 상태(Deadlock)** 발생 | 가상 채널(Virtual Channel)을 뚫어서 패킷이 막히면 갓길로 돌려버리는 순서화 라우팅 적용 | 꼬리물기로 네트워크 전체가 뻗어버리는 재앙을 원천 차단하고 순환 뚫어냄 |
| 팻트리 만들려다 꼭대기 비싼 스위치와 광케이블 값이 천문학적으로 치솟아서 파산 위기 | 윗선 대역폭을 일부러 살짝 줄이는 **초과 가입(Oversubscription)** 꼼수 타협 | 안 쓰는 트래픽 마진을 쳐내서 수백억 원짜리 구축 단가 방어 |
| GPU 수만 대가 한 번에 **올-리듀스** 때리다가 특정 스위치(핫스팟)가 불타 터지기 직전 발발 | 스위치가 막히면 덜 막히는 길로 알아서 피해 가는 **적응형 라우팅** 강제 발동 | 패킷을 이리저리 찢고 분산시켜서 핫스팟 폭주를 씹어먹음 |

#### 한줄 요약

- 꼬리물기(Deadlock)는 가상 채널로 빼고, 비용 폭발은 윗선 병목 살짝 허용(초과 가입)해서 돈을 아껴라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **토폴로지 선택 기준(Interconnect Topology Selection Criteria)**: GPU들이 다 같이 패싸움을 하는지(올-리듀스), 아니면 옆집 애랑만 노는지(그리드) 따져서 망을 어떻게 깔지 정하는 잣대이다.

</details>

- **토폴로지 선택 기준** 원칙에 따라, 대규모 집단 통신이 생명인 AI 서버는 닥치고 **팻트리**, 옆집 계산이 많은 구조는 가성비 **토러스** 채택 기조 확립함

#### 한줄 요약

- 수만 대가 한 번에 데이터 섞으려면 돈 발라서 팻트리 깔고, 옆집 통신 위주면 토러스로 묶어라.
