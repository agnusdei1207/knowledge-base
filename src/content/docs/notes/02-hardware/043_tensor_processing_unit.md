## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TPU(Tensor Processing Unit)**: 구글이 딥러닝 텐서 연산 및 행렬 곱셈을 가속하기 위해 자체 개발한 도메인 특화 ASIC.
- **XLA(Accelerated Linear Algebra)**: 텐서 연산 그래프를 분석하여 연산자를 융합하고 하드웨어 맞춤 기계어로 컴파일하는 가속 엔진.

</details>

- 정의/개념: 딥러닝 텐서 곱셈을 가속하기 위해 **시스톨릭 어레이(MXU)** 와 HBM을 결합한 도메인 특화 ASIC 프로세서
- 배경/필요성: 거대 AI 모델 학습 시 범용 GPU의 메모리 대역폭 한계 극복 및 대규모 분산 텐서 연산 가속화 필요

#### 한줄 요약
- 구글이 AI 행렬 곱셈에 최적화해 만든 전용 칩으로, 시스톨릭 어레이와 광통신망으로 거대 모델을 학습한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MXU(Matrix Multiply Unit)**: 128x128 크기의 2차원 시스톨릭 어레이로 행렬 곱셈을 한 클록마다 누산하는 전용 연산기.
- **ICI(Inter-Core Interconnect)**: TPU 칩들을 광 회로 스위치(OCS)로 직접 묶어 슈퍼컴퓨터급 팟(Pod)을 구성하는 전용 통신망.

</details>

- **시스톨릭 어레이(MXU)** 기반 2차원 행렬 곱셈(GEMM) 고속 처리
- **XLA 컴파일러**를 통한 텐서 연산 융합(Fusion) 및 메모리 최적화
- **ICI(Inter-Core Interconnect)** 기반 광스위칭 대규모 팟(Pod) 확장성

#### 한줄 요약
- 거대한 시스톨릭 행렬 곱셈기와 XLA 컴파일러, 칩 간 고속 광통신망이 결합되어 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **VPU(Vector Processing Unit)**: 활성화 함수, 정규화(LayerNorm), 소프트맥스 등 벡터 연산을 전담하는 유닛.
- **TPU Pod**: 수천 개의 TPU 칩을 2D/3D 토러스 망으로 결합하여 단일 슈퍼컴퓨터처럼 동작시키는 대규모 클러스터.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ TPU 코어 (TPU Core Architecture)                            │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ 고대역폭 메모리 (HBM3 / HBM2e Subsystem)              │  │
│  └──────────────────────────┬────────────────────────────┘  │
│                             │ (고속 메모리 인터페이스)     │
│  ┌──────────────────────────┴────────────────────────────┐  │
│  │ 벡터 메모리 (Vector Memory / DMA Router)              │  │
│  └───────────┬───────────────────────────┬───────────────┘  │
│              ▼                           ▼                  │
│  ┌───────────────────────┐   ┌───────────────────────┐      │
│  │ 행렬 곱셈 유닛 (MXU)  │──>│ 벡터 처리 유닛 (VPU)  │      │
│  │ (128x128 Systolic)    │   │ (Vector ALU / Act)    │      │
│  └───────────────────────┘   └───────────┬───────────┘      │
│              ▲                           │                  │
│              └───────────────────────────┴───────────────┐  │
│                                                          │  │
│  ┌───────────────────────────────────────────────────────┴┐ │
│  │ 스칼라 유닛 (Scalar Core) & ICI 인터커넥트 라우터      │ │
│  └──────────────────────────┬─────────────────────────────┘ │
└─────────────────────────────┼───────────────────────────────┘
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ ICI 칩 간 광학 인터커넥트 (Optical Circuit Switch / Pod 망)   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: HBM에서 벡터 메모리를 거쳐 MXU와 VPU로 전달되며 하단 ICI를 통해 대규모 Pod 클러스터 확장

| 구성요소 | 책임 |
|:---|:---|
| 행렬 곱셈 유닛 (MXU) | 128x128 격자 시스톨릭 구조로 bfloat16 행렬 곱셈 고속 수행 |
| 벡터 처리 유닛 (VPU) | 활성화 함수(GELU), 배치 정규화, 소프트맥스 벡터 연산 전담 |
| 스칼라 처리 유닛 (SU) | 루프 카운팅, 주소 계산 및 분기 제어 명령어 실행 |
| 고대역폭 메모리 (HBM) | 대규모 가중치 파라미터를 보관하고 초고속 대역폭 공급 |
| 칩 간 인터커넥트 (ICI) | CPU/호스트 경유 없이 TPU 칩 간 직접 텐서 교환 및 Pod 확장 |

#### 한줄 요약
- MXU 행렬 곱셈기, VPU 벡터 연산기, HBM, ICI 전용 통신망이 단일 칩 내에 긴밀히 통합되어 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연산자 융합(Operator Fusion)**: 여러 개의 작은 연산(곱셈+덧셈+ReLU)을 하나의 통합 커널로 합쳐 HBM 접근을 없애는 최적화.

</details>

```text
JAX / TensorFlow 모델 그래프 정의
      │
      ▼
1. XLA 컴파일러: 연산자 융합 및 HLO(High-Level Optimizer) 최적화
      │
      ▼
2. HBM에서 모델 가중치 인출 및 MXU 시스톨릭 레지스터 적재
      │
      ▼
3. 입력 데이터 스트리밍 및 MXU 2D 행렬 곱셈 동시 수행
      │
      ▼
4. VPU: 활성화 함수 및 정규화 연산 파이프라인 처리
      │
      ▼
5. ICI 인터커넥트: TPU Pod 전체 All-Reduce 동기화 및 결과 갱신
```

**동작 원리**

1. **그래프 최적화**: XLA가 AI 모델의 계산 그래프를 분석해 불필요한 중간 텐서 저장을 제거하고 연산자 융합
2. **가중치 적재**: HBM에 저장된 가중치 블록을 읽어 MXU의 시스톨릭 어레이에 배치
3. **행렬 곱셈**: 입력 데이터가 시스톨릭 셀들을 통과하며 곱셈과 누산을 동시에 수행
4. **벡터 처리**: MXU 출력 결과에 VPU가 활성화 함수와 정규화를 즉시 적용하여 캐시에 보관
5. **집단 통신**: 대규모 분산 학습 시 ICI 광스위칭 망을 통해 All-Reduce로 가중치 기울기 실시간 동기화

#### 한줄 요약
- XLA 그래프 융합 → MXU 시스톨릭 곱셈 → VPU 활성화 처리 → ICI 광통신 동기화 순으로 진행된다.

## Ⅴ. 종류 및 비교

| AI 가속 프로세서 | Google TPU | NVIDIA GPU | 온디바이스 NPU | 범용 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | 구글 클라우드 기반 초대형 LLM 학습/추론 | 범용 AI 프레임워크 및 다양한 HPC 가속 | 모바일·임베디드 초저전력 실시간 추론 | 범용 연산 및 복잡한 제어 중심 태스크 |
| 핵심 특징 | 대규모 MXU 시스톨릭 어레이 및 ICI Pod 확장 | 범용 SIMT 코어 및 방대한 CUDA 생태계 | 극저전력 NPU 코어 및 SoC 온칩 집적 | 직렬 명령어 고속 디코딩 및 다단계 캐시 |
| 한계 | 구글 클라우드 환경 종속성·타 프레임워크 제약 | 높은 소비 전력 및 분산 통신 인프라 비용 | 온칩 SRAM 용량 한계로 거대 모델 구동 불가 | 텐서 병렬 연산 대역폭 절대 부족 |

#### 한줄 요약
- 구글 클라우드 거대 모델은 TPU, 범용 생태계는 GPU, 모바일 추론은 NPU, 범용 제어는 CPU를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **bfloat16**: 부동소수점 표현에서 FP32와 동일한 지수부 범위를 유지하면서 가수부를 7비트로 줄여 행렬 곱셈 효율을 극대화한 포맷.
- **Shape Bucketing**: 가변 입력 길이를 고정된 버킷 크기로 패딩하여 XLA의 잦은 재컴파일을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 데이터 길이 변동 시 **XLA 재컴파일** 오버헤드 | **Shape Bucketing** 및 고정 패딩(Padding) 전략 적용 | 런타임 컴파일 지연 제거 및 일정한 처리율 유지 |
| 거대 모델 분산 학습 시 노드 간 통신 병목 | **ICI 토러스 망** 기반 텐서/파이프라인 병렬화 구성 | 팟(Pod) 단위 선형 확장성 및 All-Reduce 가속 |
| FP32 부동소수점 연산 시 메모리 대역폭 포화 | **bfloat16** 기본 데이터 타입 채택 및 혼합 정밀도 적용 | 대역폭 절감 및 MXU 연산 처리량 2배 향상 |
| 비표준 커스텀 레이어의 TPU 미지원 연산자 발생 | JAX 기반 커스텀 Pallas 커널 작성 및 XLA 호환 매핑 | TPU 전용 하드웨어 가속기 활용성 보장 |

#### 한줄 요약
- Shape Bucketing으로 컴파일 지연을 없애고, ICI 토러스로 통신을 뚫으며, bfloat16으로 대역폭을 절약한다.

## Ⅶ. 결론

- 초대규모 LLM 분산 학습 및 구글 클라우드 인프라는 **TPU Pod**, 범용 다중 프레임워크는 **GPU** 선택

#### 한줄 요약
- XLA 연산자 융합과 bfloat16 정밀도, ICI 광통신망을 종합 연계하여 초대규모 AI 학습 인프라를 최적화해야 한다.
