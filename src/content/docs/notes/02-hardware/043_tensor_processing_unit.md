## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TPU(Tensor Processing Unit)**: Google이 딥러닝 텐서 행렬 곱셈을 가속하기 위해 자체 설계한 데이터센터용 도메인 특화 ASIC.
- **텐서(Tensor)**: 다차원 배열 데이터 구조로, 신경망 가중치와 활성화 맵을 표현하는 수학적 기본 단위.
- **행렬 연산 전용 가속(Matrix-Specialized Acceleration)**: 범용 스레드 제어 오버헤드를 제거하고 2D 하드웨어 격자(시스톨릭 배열) 위에서 행렬 곱셈을 직결 처리하는 구조.

</details>

- 정의/개념: 심장 박동처럼 피연산자를 전달하는 2D 시스톨릭 배열(Systolic Array) MXU와 전용 도메인 특화 컴파일러(XLA)를 결합하여, 딥러닝 텐서 행렬 연산에 극대화 최적화된 Google의 전용 AI 가속기(ASIC)
- 배경/필요성: 범용 GPU의 범용 렌더링/스레드 오버헤드를 배제하고, **데이터센터 레벨에서 대규모 딥러닝 학습/추론의 에너지 효율(TOPS/W) 및 초대형 클러스터(Pod) 확장성 확보**

#### 한줄 요약

- 2D 시스톨릭 배열(MXU)과 XLA 컴파일러로 **딥러닝 텐서 행렬 곱셈을 가속하는 Google 전용 ASIC**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **XLA(Accelerated Linear Algebra)**: 고수준 텐서 그래프를 분석하여 연산자를 융합(Fusion)하고 메모리 이동을 최소화하는 TPU 전용 최적화 컴파일러.
- **Systolic Array (MXU)**: 데이터가 인접 PE 간에 매 클록마다 전달되며 곱셈과 누산을 연속 수행하는 $128 \times 128$ 또는 $256 \times 256$ 크기의 2D 행렬 곱셈기.
- **ICI(Inter-Chip Interconnect)**: TPU 칩 간에 호스트 CPU나 PCIe 버스 개입 없이 3D 토러스(Torus) 네트워크로 직접 연결하는 초고속 전용 인터커넥트.

</details>

- 연산 그래프를 분석하여 메모리 왕복 트랜잭션을 제거하는 **XLA(Accelerated Linear Algebra)** 컴파일러 통합
- 피연산자를 레지스터 간에 직접 전달하여 메모리 접근 에너지를 억제하는 **2D 시스톨릭 배열(MXU)** 기반 행렬 곱셈 가속
- 칩 간 통신 병목을 해결하기 위한 온패키지 **HBM 고대역폭 메모리** 및 광학 3D 토러스 **ICI(Inter-Chip Interconnect)** 내장

#### 한줄 요약

- **시스톨릭 MXU·XLA 컴파일러(연산자 융합)·HBM 고대역폭·ICI 토러스 인터커넥트**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Vector Unit(VPU)**: MXU에서 나온 행렬 곱셈 결과에 대해 활성화 함수(ReLU, GELU), 정규화(LayerNorm), 소프트맥스 등의 비선형 벡터 연산을 수행하는 유닛.
- **TPU Pod**: 수백~수천 개의 TPU 칩을 전용 ICI 패브릭과 광 회로 스위치(OCS)로 묶어 단일 거대 슈퍼컴퓨터로 동작시키는 클러스터 단위.

</details>

```text
[ TPU 칩 및 XLA 컴파일러 소프트웨어 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ AI 프레임워크 계층 (JAX, TensorFlow, PyTorch/XLA)          │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ XLA 컴파일러 (그래프 연산자 융합, 타일링, 샤딩 최적화)      │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────┴──────────────────────────────┐
│ TPU 칩 하드웨어 내부                                        │
│  ├─ 대용량 고대역폭 메모리 (HBM3 : 수십 GB, 수 TB/s)        │
│  │    │                                                     │
│  │    ▼                                                     │
│  ├─ Matrix Multiply Unit (MXU : 128x128 2D 시스톨릭 배열)   │
│  │    │ (Weight-Stationary 행렬 곱셈)                       │
│  │    ▼                                                     │
│  ├─ Vector Processing Unit (VPU : ReLU, GELU, Softmax 연산)  │
│  │    │                                                     │
│  │    ▼                                                     │
│  └─ Inter-Chip Interconnect (ICI Router : 3D 토러스 링크)   │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: XLA 컴파일러, Host 런타임, TPU MXU/VPU 연산 코어, HBM 메모리 및 ICI 인터커넥트 간의 TPU 시스템 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 가속 선형 대수 컴파일러 | 분절된 거대 그래프 연산을 융합하고, 텐서를 칩 사이즈에 맞게 자르고(타일링), 여러 칩에 분배하는(샤딩) 최적화 기계어 코드 생성 |
| 텐서 처리 장치 런타임 | 구글 클라우드 호스트와의 통신, 컴파일된 최적화 커널을 칩에 던져넣기(런칭), 및 장치 온도/가동률 메트릭 감시 모니터링 |
| 행렬 곱셈 유닛 및 벡터 유닛 | 무자비한 시스톨릭 바둑판 2차원 행렬 곱 연산 집중 수행 및 그 결과값에 비선형 활성화 함수 수학 연산 후처리 |
| 고대역폭 메모리 및 칩 간 인터커넥트 | 행렬 곱셈 유닛에 텐서를 폭포수처럼 고속 스트리밍 공급 및 토러스 망 기반 분산 칩 간 막대한 파라미터 데이터 동기화 |

#### 한줄 요약

- **XLA 컴파일러·TPU 런타임·MXU(시스톨릭 어레이)·VPU(벡터)·HBM·ICI(칩 간 통신)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **All-Reduce Collective**: 분산된 수천 개의 TPU 칩들이 각자의 그래디언트(Gradient)를 전용 ICI 네트워크를 통해 일괄 합산 및 브로드캐스트하는 집단 통신 연산.

</details>

```text
[ TPU 딥러닝 연산 및 클러스터 동기화 흐름 ]
                         │
                         ▼
   [ 1. XLA 컴파일러의 연산 그래프 융합 및 타일링/샤딩 최적화 ]
                         │
                         ▼
   [ 2. 칩 내부 온패키지 HBM에 가중치 및 활성화 텐서 고속 적재 ]
                         │
                         ▼
   [ 3. MXU 2D 시스톨릭 배열로 피연산자 스트리밍 주입 및 행렬 연산 ]
                         │
                         ▼
   [ 4. VPU에서 활성화 함수(GELU) 및 정규화(LayerNorm) 벡터 후처리 ]
                         │
                         ▼
   [ 5. 다중 칩 Pod 환경에서 ICI 3D 토러스 기반 All-Reduce 동기화 ]
```

**동작 원리**

1. **그래프 컴파일**: XLA 컴파일러가 PyTorch/JAX의 연산 그래프를 분석하여 연산자 융합 및 타일링 기계어 생성
2. **HBM 적재**: 호스트와 DMA를 통해 입력 텐서 및 모델 가중치를 HBM에 고속 로드
3. **MXU 시스톨릭 연산**: 2차원 시스톨릭 PE 배열을 통과하며 클록마다 행렬 곱셈과 부분합 누적 수행
4. **VPU 벡터 처리**: MXU 연산 결과에 대해 활성화 함수 및 정규화 등의 벡터 연산 즉각 처리
5. **ICI 집단 통신**: TPU Pod 내 수천 개 칩 간에 전용 ICI 링크로 All-Reduce 집단 통신을 수행하여 가중치 동기화

#### 한줄 요약

- XLA 그래프 융합 $\to$ **HBM 텐서 배치 $\to$ MXU 시스톨릭 행렬 연산 $\to$ VPU 활성화 $\to$ ICI All-Reduce 동기화**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TPU vs GPU vs NPU**:
  - TPU: 2D 시스톨릭 배열, XLA 전용 컴파일러, 초거대 TPU Pod 확장성
  - GPU: SIMT 멀티스레딩, 범용 CUDA 생태계, 높은 배치 처리량
  - NPU: 초소형 경량화, 모바일 온디바이스 저전력 추론 특화

</details>

| 비교 항목 | TPU (Google ASIC) | GPU (NVIDIA H100) | NPU (On-Device NPU) |
|:---|:---|:---|:---|
| 아키텍처 및 코어 구조 | 2D 시스톨릭 배열 (MXU) + XLA 그래프 컴파일 | SIMT 멀티스레딩 + Tensor Core (CUDA 생태계) | 경량화된 저전력 MAC 어레이 (하드와이어드) |
| 메모리 및 확장 인터커넥트 | HBM3 + 광학 ICI (3D Torus 토폴로지 TPU Pod) | HBM3 + NVLink / NVSwitch + InfiniBand | 온칩 SRAM + LPDDR5 (초저전력 단일 칩 중심) |
| 한계 및 소프트웨어 종속 | Google 프레임워크(TensorFlow/JAX) 강력한 종속 | 높은 전력 소모(700W) 및 인프라 구축 비용 | 고정된 연산자 지원 한계 및 작은 메모리 용량 |

#### 한줄 요약

- Google 클라우드 거대 모델은 **TPU**, 범용 AI/생태계는 **GPU**, 모바일 에지는 **NPU**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Shape Bucketing**: 가변 길이 입력 시 발생하는 XLA 잦은 재컴파일(JIT 오버헤드)을 방지하기 위해 입력 크기를 고정 단위 버킷(32, 64, 128)으로 패딩하는 기법.
- **SPMD(Single Program Multiple Data) Sharding**: 거대한 LLM 파라미터를 텐서/파이프라인 단위로 쪼개어 수천 개 TPU 칩에 분산하는 병렬화 패러다임.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 텍스트나 이미지 입력 텐서 셰이프가 가변으로 들어와 칩이 매번 **가속 선형 대수** 재컴파일을 시도하며 폭주하고 뻗어버리는 지연 현상 | 입력 데이터를 정해진 크기로 **모양 버킷화**하여 고정 패딩하고, 번역 결과를 **컴파일 캐시** 시스템에 강제 저장 및 재사용 적용 | 모델 런타임 런칭 시 수 분이 걸리는 컴파일 지연시간 원천 제거 및 실행 일관성 방어 달성 |
| 구글 칩이 지원 불가한 듣도 보도 못한 신규 연산자 포함에 따른 호스트 우회 **폴백** 발생 및 처참한 성능 병목 지연 | 텐서플로우/JAX 커널 그래프 소프트웨어 뼈대를 칩에 맞게 리팩토링하고 TPU가 알아먹는 대체 호환 연산자로 전환 설계 | 프로세서(CPU-TPU) 간 엄청난 텐서를 톨게이트로 밀어내는 불필요한 데이터 이송 및 통신 병목 원천 차단 |
| 행렬 크기를 잘못 잡아 고속 메모리 대역폭이 꽉 차버리고 수만 개 연산 코어가 손가락 빨고 노는 가동률 추락 참사 | **가속 선형 대수** 연산자 융합 최적화 강제 먹이기 및 타일 크기를 바둑판에 딱 맞게 재조정하여 온칩 텐서 점유율 극한 통제 | 칩 밖으로 안 나가고 칩 내부 온칩 텐서 재사용성을 폭발적으로 증대시켜 끔찍한 메모리 바운드 족쇄 완화 |
| 거대 모델 학습 시 다중 칩 클러스터 간 대규모 파라미터 분산 통신 동기화가 막혀서 전체 포드가 멈춰버리는 병목 현상 | 전용 컴파일러를 통한 모델 **샤딩** 패턴 악착같은 최적화 및 연산기(MXU)의 계산과 인터커넥트 통신의 완벽한 중첩 기법 구현 | 통신이 연산 발목을 잡지 않게 만들어, 칩을 수천 개 꽂아도 선형적으로 빨라지는 대규모 클러스터 스케일아웃 확장 효율성 극대화 |

#### 한줄 요약

- **Shape Bucketing(재컴파일 방지)·호환 연산자 대체·타일링 최적화·ICI 샤딩(SPMD)**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **OCS(Optical Circuit Switching)**: TPU v4/v5p Pod에서 전기 신호 변환 없이 빛(Optical) 신호 자체를 미러로 편향시켜 3D 토러스 토폴로지를 동적으로 재구성하는 차세대 광학 스위칭 기술.

</details>

- 초대규모 분산 학습 및 JAX/TF 환경에서 **TPU v4/v5p Pod 및 OCS 광스위치 기반 확장 아키텍처 표준 채택**

#### 한줄 요약

- **워크로드 규모, 전력 효율성, 소프트웨어 프레임워크 종속성**을 고려한 TPU 도입
