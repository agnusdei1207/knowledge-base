## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TPU(Tensor Processing Unit)**: 구글이 딥러닝 텐서 연산 및 행렬 곱셈을 가속하기 위해 자체 개발한 도메인 특화 ASIC.
- **XLA(Accelerated Linear Algebra)**: 텐서 연산 그래프를 분석하여 연산자를 융합하고 하드웨어 맞춤 기계어로 컴파일하는 가속 엔진.

</details>

- 정의/개념: 행렬 곱셈 전용 **MXU(Matrix Multiply Unit)**와 고대역폭 메모리, 칩 간 전용망을 함께 설계한 도메인 특화 ASIC인 **TPU(Tensor Processing Unit)**
- 배경/필요성: 대규모 모델 학습은 연산기 성능만으로 빨라지지 않고 메모리 이동과 가속기 간 집단 통신이 실제 시간을 지배

#### 한줄 요약
- TPU가 다른 가속기와 갈리는 지점은 연산기가 아니라 칩 여러 개를 한 대처럼 쓰기 위한 통신망을 처음부터 설계에 넣었다는 데 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MXU(Matrix Multiply Unit)**: 2차원 시스톨릭 어레이로 행렬 곱셈·누산을 수행하는 전용 연산기.
- **ICI(Inter-Chip Interconnect)**: TPU 칩들을 직접 연결해 팟(Pod)을 구성하는 전용 칩 간 통신망.

</details>

- MXU 시스톨릭 구조로 중간값을 메모리에 내리지 않고 행렬 곱셈 처리
- **XLA(Accelerated Linear Algebra)**가 연산 그래프를 융합해 메모리 왕복 제거
- **ICI(Inter-Chip Interconnect)** 기반 대규모 팟(Pod) 확장성

#### 한줄 요약
- 하드웨어와 컴파일러가 같은 조직에서 함께 설계됐다는 사실이 성능의 근거이자 종속성의 근거이며, 두 성질이 분리되지 않는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **VPU(Vector Processing Unit)**: 활성화 함수, 정규화(LayerNorm), 소프트맥스 등 벡터 연산을 전담하는 유닛.
- **TPU Pod**: 수천 개의 TPU 칩을 2D/3D 토러스 망으로 결합하여 단일 슈퍼컴퓨터처럼 동작시키는 대규모 클러스터.

</details>

```text
[TPU 코어]
├─ 고대역폭 메모리 (HBM)
├─ 벡터 메모리·DMA 라우터
├─ 연산 유닛
│  ├─ MXU (시스톨릭 행렬 곱셈)
│  ├─ VPU (활성화·정규화·소프트맥스)
│  └─ 스칼라 유닛 (주소 계산·분기 제어)
└─ ICI 라우터
   └─ TPU Pod (칩 간 토러스 망)
```

선의 의미: 가지(`├─`)는 소유 관계이며, ICI 라우터만이 칩 경계를 넘어 다른 TPU와 직접 이어짐

| 구성요소 | 책임 |
|:---|:---|
| MXU | 시스톨릭 구조로 저정밀 행렬 곱셈·누산 수행 |
| **VPU(Vector Processing Unit)** | 활성화·정규화·소프트맥스 벡터 연산 전담 |
| 스칼라 유닛 | 루프 카운팅·주소 계산·분기 제어 실행 |
| 고대역폭 메모리 (HBM) | 대규모 가중치와 활성화 텐서에 메모리 대역폭 공급 |
| **ICI(Inter-Chip Interconnect)** | 호스트를 거치지 않는 칩 간 텐서 교환과 **TPU Pod** 확장 |

#### 한줄 요약
- 스칼라 유닛이 가장 작지만 없으면 나머지가 아무것도 하지 못하듯, 도메인 특화 칩에서도 범용 제어는 완전히 사라지지 않고 최소한으로 남는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연산자 융합(Operator Fusion)**: 여러 개의 작은 연산(곱셈+덧셈+ReLU)을 하나의 통합 커널로 합쳐 HBM 접근을 없애는 최적화.

</details>

```text
JAX·TensorFlow 모델 그래프 정의
        │
   XLA가 그래프 분석 후 연산자 융합
        │
   HBM에서 가중치를 MXU에 적재하고 입력 주입
        │
   MXU 누산 결과에 VPU가 활성화·정규화 적용
        │
   단일 칩으로 끝나는가?
   ┌────┴─────┐
  예           아니오 (분산 학습)
   │             │
결과 반환      ICI로 기울기 All-Reduce 동기화
   │             │
   └────┬────────┘
        │
   다음 스텝 진행
```

분기 결과: 단일 칩 구간은 연산기 성능이 상한을 정하지만 분산 구간에서는 ICI 대역폭이 상한을 정하므로, 모델이 커질수록 병목이 연산에서 통신으로 넘어감

#### 한줄 요약
- **연산자 융합(Operator Fusion)**이 맨 앞에 오는 이유는 뒤 단계의 메모리 접근량을 줄이는 유일한 지점이기 때문이며, 여기서 놓친 왕복은 하드웨어로 만회되지 않는다.

## Ⅴ. 종류 및 비교

| AI 가속 프로세서 | Google TPU | NVIDIA GPU | 온디바이스 NPU | 범용 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | 구글 클라우드 기반 초대형 LLM 학습/추론 | 범용 AI 프레임워크 및 다양한 HPC 가속 | 모바일·임베디드 초저전력 실시간 추론 | 범용 연산 및 복잡한 제어 중심 태스크 |
| 핵심 특징 | 대규모 MXU 시스톨릭 어레이 및 ICI Pod 확장 | 범용 SIMT 코어 및 방대한 CUDA 생태계 | 극저전력 NPU 코어 및 SoC 온칩 집적 | 직렬 명령어 고속 디코딩 및 다단계 캐시 |
| 한계 | 구글 클라우드 환경 종속성·타 프레임워크 제약 | 높은 소비 전력 및 분산 통신 인프라 비용 | 온칩 SRAM 용량 한계로 거대 모델 구동 불가 | 텐서 병렬 연산 대역폭 절대 부족 |

#### 한줄 요약
- 네 프로세서의 선택은 성능 순위가 아니라 모델 크기와 배포 환경이 정하며, TPU의 강점인 확장성은 그 규모에 도달하지 못한 조직에는 값이 없다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **bfloat16**: 부동소수점 표현에서 FP32와 동일한 지수부 범위를 유지하면서 가수부를 7비트로 줄여 행렬 곱셈 효율을 극대화한 포맷.
- **Shape Bucketing**: 가변 입력 길이를 고정된 버킷 크기로 패딩하여 XLA의 잦은 재컴파일을 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 길이가 바뀔 때마다 XLA 재컴파일 발생 | **Shape Bucketing**으로 고정 크기 패딩 적용 | 컴파일 형태 수와 지연 변동 감소 |
| 거대 모델 분산 학습에서 칩 간 통신 병목 | ICI 토폴로지에 맞춰 텐서·파이프라인 병렬화 배치 | 연산량과 집단 통신량 균형 조정 |
| FP32 연산으로 대역폭과 연산량 동시 증가 | **bfloat16** 혼합 정밀도와 손실 스케일링 적용 | 정확도 유지 범위에서 데이터 이동량 감소 |
| 비표준 레이어의 TPU 미지원 연산자 발생 | XLA 지원 연산으로 재구성하거나 커스텀 커널 작성 | 호스트 폴백과 그래프 분할 비용 감소 |

#### 한줄 요약
- 네 문제 중 셋이 컴파일러와 정밀도 선택에서 나오므로, TPU 성능 작업의 무게중심은 하드웨어 튜닝이 아니라 그래프를 컴파일러가 좋아하는 모양으로 유지하는 데 있다.

## Ⅶ. 결론

- XLA 호환성과 칩 간 통신 효율이 검증된 대규모 학습은 **TPU Pod**를 선택하고, 커스텀 연산이나 프레임워크 이동성이 중요하면 GPU 생태계와 총소유비용을 함께 비교

#### 한줄 요약
- TPU 채택의 실제 관문은 성능이 아니라 모델 코드가 XLA가 컴파일할 수 있는 형태인지이며, 이 조건을 못 맞추면 하드웨어는 손도 대지 못한다.
