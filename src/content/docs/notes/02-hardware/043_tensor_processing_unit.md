## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **텐서 처리 장치(Tensor Processing Unit)**: 구글이 오직 딥러닝의 거대한 텐서 행렬 곱셈만을 미친 듯이 쳐내기 위해 자체 설계하고 데이터센터에 깔아버린 구글 전용 인공지능 맞춤형 반도체(ASIC)이다.
- **텐서(Tensor)**: 인공지능이 세상을 이해하는 방식인 1차원 벡터, 2차원 행렬을 넘어선 3차원 이상의 복잡하고 거대한 다차원 데이터 덩어리이다.
- **행렬 연산 전용 가속(Matrix-Specialized Acceleration)**: 스레드를 복잡하게 굴리는 그래픽 카드(GPU)와 달리, 데이터가 칩 안의 2차원 파이프라인을 맥박(시스톨릭)처럼 흘러가며 연산을 끝내버리는 극한의 특화 구조이다.

</details>

- 정의: 심장 박동처럼 피연산자를 흘려보내는 시스톨릭 행렬 연산 아키텍처와 전용 컴파일러를 결합하여, 신경망 텐서 연산만을 특화하여 처리하는 **텐서 처리 장치** 가속기
- 배경: 그래픽 렌더링 찌꺼기가 남아있는 범용 그래픽 처리 장치(GPU)를 치워버리고, 구글 데이터센터 인프라 차원에서 딥러닝 행렬 연산의 전력 효율과 처리량을 무자비하게 극대화하기 위함

#### 한줄 요약

- 범용성을 완전히 내다 버리고, 딥러닝의 90%를 차지하는 '행렬 곱셈' 하나만을 칩의 물리적 바둑판 배열 위에서 빛의 속도로 쳐내기 위해 구글이 창조한 괴물 반도체이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가속 선형 대수(Accelerated Linear Algebra)**: 파이썬 코드를 칩이 알아먹는 기계어로 번역할 때, 떨어져 있는 연산들을 하나로 뭉치고 찌그러뜨려 칩 안에서 한 번에 쳐내게 만드는 악독한 전용 컴파일러이다.
- **시스톨릭 배열(Systolic Array)**: 수만 개의 연산기가 바둑판처럼 깔려, 데이터가 마치 심장 박동(Systole)에 맞춰 피가 혈관을 흐르듯 인접한 연산기로 찰칵찰칵 넘어가며 행렬을 곱하는 아키텍처이다.
- **고대역폭 메모리(High Bandwidth Memory)**: 칩 옆에 느려터진 메모리를 넓게 까는 대신, 메모리 칩을 수직으로 겹겹이 쌓아 올려 미친 듯한 대역폭으로 텐서 데이터를 폭포수처럼 쏟아붓는 괴물 램이다.
- **칩 간 인터커넥트(Inter-Chip Interconnect)**: 구글 텐서 처리 장치들끼리 거대한 딥러닝 모델을 나눠 풀기 위해, 칩과 칩의 옆구리를 전용 광케이블로 직결하여 막힘없이 데이터를 주고받는 고속도로이다.
- **행렬 곱셈 유닛(Matrix Multiply Unit)**: 텐서 처리 장치 칩 한가운데 박혀있는 심장으로, 오로지 거대한 2차원 행렬을 때려 넣고 한 번에 곱셈을 수행하는 무식한 하드웨어 블록이다.

</details>

- 연산 그래프를 분석하여 여러 연산을 한 번에 융합하고, 거대한 텐서를 타일링 및 샤딩으로 자동 분해하는 **가속 선형 대수** 컴파일 도구 체계를 내장함.
- 수만 개의 연산기가 오와 열을 맞춘 **시스톨릭 배열** 기반 **행렬 곱셈 유닛** 하드웨어를 통해, 데이터를 바깥으로 빼지 않고 칩 내부에서 돌려막으며 2차원 행렬 곱을 극한으로 가속함.
- 연산기가 굶어 죽지 않도록 막대한 데이터를 펌핑하는 3D 수직 적층 **고대역폭 메모리** 및, 수백 개의 칩을 엮어 거대 뇌를 만드는 **칩 간 인터커넥트**를 장착함.

#### 한줄 요약

- 컴파일러(XLA)가 코드를 하나로 뭉치고, 바둑판 배열(시스톨릭)이 행렬을 갈아버리며, 적층 메모리(HBM)와 칩 간 광케이블(ICI)이 데이터 굶주림을 해결하는 삼위일체 구조이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **벡터 유닛(Vector Unit)**: 무식한 행렬 곱셈 유닛(MXU)이 1차 연산을 끝내면, 뒤이어 렐루(ReLU)나 소프트맥스(Softmax) 같은 딥러닝 특유의 비선형 함수를 발라주는 뒤처리 전담 연산기이다.
- **텐서 처리 장치 런타임(TPU Runtime)**: 중앙 처리 장치(CPU) 쪽에서 대기하며, 컴파일이 끝난 작업을 칩으로 던져주고 온도가 올라가진 않는지 칩 상태를 감시하는 매니저 프로그램이다.

</details>

```text
[ 텐서 처리 장치 소프트웨어 컴파일 및 하드웨어 연산 프레임워크 ]
       [ 인공지능 프레임워크 (TensorFlow, JAX 등) ]
                               │
                               ▼
   [ 가속 선형 대수(XLA) 그래프 융합 및 타일링 컴파일러 ]
                               │
                               ▼
   [ 호스트 런타임 (커널 런칭 및 칩 직접 메모리 접근 통제) ]
                               │
                               ▼
+-------------------------------------------------------------+
| 텐서 처리 장치(TPU) 하드웨어 내부                           |
|                                                             |
|       [ 고대역폭 메모리(HBM) 초고속 텐서 공급 버퍼 ]        |
|             │                               │               |
|             ▼                               ▼               |
| [ 시스톨릭 행렬 곱셈 유닛(MXU) ] ──> [ 비선형 벡터 유닛 ]   |
|             │                               │               |
|             └──────> [ 칩 간 인터커넥트(ICI) 다중 칩 통신 ] |
+-------------------------------------------------------------+
```

| 구성요소 | 책임 |
|:---|:---|
| **가속 선형 대수** 컴파일러 | 분절된 거대 그래프 연산을 융합하고, 텐서를 칩 사이즈에 맞게 자르고(타일링), 여러 칩에 분배하는(샤딩) 최적화 기계어 코드 생성 |
| **텐서 처리 장치 런타임** | 구글 클라우드 호스트와의 통신, 컴파일된 최적화 커널을 칩에 던져넣기(런칭), 및 장치 온도/가동률 메트릭 감시 모니터링 |
| **행렬 곱셈 유닛** 및 **벡터 유닛** | 무자비한 시스톨릭 바둑판 2차원 행렬 곱 연산 집중 수행 및 그 결과값에 비선형 활성화 함수 수학 연산 후처리 |
| **고대역폭 메모리** 및 **칩 간 인터커넥트** | 행렬 곱셈 유닛에 텐서를 폭포수처럼 고속 스트리밍 공급 및 토러스 망 기반 분산 칩 간 막대한 파라미터 데이터 동기화 |

#### 한줄 요약

- 코드를 칩에 맞게 으깨고 뭉치는 컴파일러(XLA), 무식하게 곱셈만 치는 MXU, 뒤처리를 하는 벡터 유닛, 그리고 거대한 칩 군단을 묶는 ICI 광망으로 이루어져 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연산 그래프(Computation Graph)**: 딥러닝 모델이 데이터를 어떻게 곱하고 더해서 결과를 낼지 화살표로 엮어놓은 거대한 지도(DAG)이다.
- **타일링(Tiling)**: 수 기가바이트짜리 텐서 데이터를 칩 안의 좁은 메모리와 바둑판 연산기 크기에 딱 들어맞도록 모자이크 타일처럼 잘게 썰어내는 기술이다.
- **집단 통신(Collective Communication)**: 수백 개의 텐서 처리 장치가 각자 학습한 텐서 조각들을 "하나, 둘, 셋" 하고 다 같이 교환해서 하나의 거대한 가중치로 뭉치는(All-Reduce) 동기화 기술이다.

</details>

```text
[ 텐서 처리 장치 연산 그래프 컴파일 및 다중 칩 클러스터 실행 흐름 ]
                               │
                               ▼
 [ 1. 가속 선형 대수 컴파일러의 연산 그래프 융합, 타일링 및 샤딩 최적화 ]
                               │
                               ▼
    [ 2. 칩 내부 고대역폭 메모리(HBM)에 텐서 파라미터 및 가중치 고속 배치 ]
                               │
                               ▼
        [ 3. 행렬 곱셈 유닛(MXU)으로 텐서 타일 데이터의 무한 스트리밍 공급 ]
                               │
                               ▼
       [ 4. 시스톨릭 바둑판 배열의 행렬 곱 병렬 연산 및 벡터 유닛 활성화 적용 ]
                               │
                               ▼
        [ 5. 다중 칩 클러스터 시 칩 간 인터커넥트(ICI) 망을 통한 집단 통신 동기화 ]
```

### 동작 원리

1. 컴파일 융합 최적화: 모델의 방대한 **연산 그래프**를 씹어먹고 불필요한 메모리 이동을 없애는 **타일링** 및 샤딩 기반 **가속 선형 대수** 컴파일을 수행함.
2. 고속 메모리 텐서 배치: 컴파일이 끝난 파라미터 및 가중치를 장치 옆에 우뚝 솟은 3D **고대역폭 메모리** 영역에 전략적으로 꽉꽉 눌러 배치함.
3. 텐서 타일 파이프라이닝: 칩이 연산을 멈추지 않도록 메모리로부터 **행렬 곱셈 유닛** 피연산자 타일 데이터를 끊임없이 스트리밍으로 펌핑 공급함.
4. 시스톨릭 행렬 병렬 연산: 박동하는 시스톨릭 배열을 통과하며 거대 곱셈을 한 번에 처리하고, 뒤이어 **벡터 유닛**에서 렐루 같은 활성화 연산을 발라버림.
5. 분산 망 칩 간 동기화: 거대 모델을 쪼개어 다중 칩을 구성할 시, 전용 **칩 간 인터커넥트** 토러스 광망을 맹렬히 가동하여 수백 개의 칩이 **집단 통신**을 완벽 동기화함.

#### 한줄 요약

- 컴파일러가 코드를 깎고 뭉쳐 칩에 욱여넣으면, 칩은 펄스처럼 데이터를 흘려보내며 행렬을 곱하고, 수백 개의 칩이 전용 광망으로 결과값을 교환하며 거대 모델을 학습한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **티피유 포드(TPU Pod)**: 텐서 처리 장치 칩 수백~수천 개를 전용 광케이블 랙으로 엮어서 거대한 초거대 AI(LLM) 하나만을 풀기 위해 구축한 축구장만 한 슈퍼컴퓨터 클러스터이다.
- **그래픽 처리 장치(Graphics Processing Unit)**: 게임 렌더링용 찌꺼기 로직이 남아 전력은 많이 먹지만, 쿠다 생태계 덕에 인공지능부터 코인 채굴까지 다방면으로 쓰이는 범용 스레드 병렬 가속기이다.
- **신경망 처리 장치(Neural Processing Unit)**: 스마트폰이나 스마트 워치 안에서 배터리를 갉아먹지 않고 얼굴 인식 같은 가벼운 딥러닝 추론만 모기 눈물만 한 전력으로 쳐내는 초소형 칩이다.

</details>

| 비교 항목 | **텐서 처리 장치** (TPU) | **그래픽 처리 장치** (GPU) | **신경망 처리 장치** (NPU) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 파라미터 수천억 개의 초거대 언어 모델을 구글 데이터센터 **티피유 포드** 기반으로 무식하게 분산 학습시킬 시 | 인공지능 모델과 알고리즘이 하루가 다르게 변하고, 쿠다 기반의 압도적인 범용 소프트웨어 생태계가 절대 필요 시 | 모바일 기기 및 스마트 카메라 등 배터리가 생명인 임베디드 단말 환경에서 극한의 저전력 추론만 돌릴 시 |
| 아키텍처 핵심 구현 특징 | 행렬에 올인한 **시스톨릭 배열** 하드웨어 및 코드를 칩에 구겨 넣는 강력한 전용 **가속 선형 대수** 컴파일러 기반 | 수천 개의 코어에 수백만 개의 스레드를 던져놓고 굴리는 단일 명령 다중 스레드(SIMT) 병렬성 기반 하드웨어 통제 | 칩 크기를 극단적으로 다이어트한 단말 장치 전용 저전력 덧셈/곱셈 연산 로직 및 하드웨어 경량화 구조체 |
| 극복해야 할 태생적 한계점 | 텐서플로우/JAX 등 구글 프레임워크 밖으로 나가면 쓰레기가 되며, 코드가 바뀔 때마다 피 말리는 재컴파일 오버헤드 발생 위협 | 그래픽을 돌리던 태생적 한계로 인한 극한의 칩 전력 소모 및 칩 밖으로 데이터를 퍼 나르다 생기는 전역 메모리 복사 통신 병목 | 복잡한 최신 딥러닝 연산자를 하드웨어가 지원하지 못해 뻗어버릴 제약과, 쿠다에 비해 처참하게 협소한 개발 도구 생태계 한계 |

#### 한줄 요약

- 구글 클라우드에서 거대 모델을 훈련시킬 땐 TPU 포드 융단폭격, 범용성과 호환성이 깡패면 GPU, 스마트폰 배터리를 아끼려면 NPU를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **모양 버킷화(Shape Bucketing)**: 텍스트 길이가 10글자, 15글자로 들쭉날쭉 들어오면 칩이 매번 새로 컴파일하며 뻗어버리니, 16글자짜리 바구니(버킷)로 억지로 패딩(여백 채우기)해서 집어넣는 꼼수이다.
- **컴파일 캐시(Compilation Cache)**: 한 번 피가 마르도록 번역해 둔(컴파일) 칩 기계어 코드를 버리지 않고 캐시에 저장해 두었다가, 똑같은 모델이 들어오면 재활용하여 런칭 시간을 0초로 만드는 기술이다.
- **폴백(Fallback)**: TPU가 모르는 희한한 연산자가 코드에 들어오면, 칩이 계산을 포기하고 멍청한 호스트 중앙 처리 장치(CPU)로 텐서를 다시 넘겨서 계산하고 받아오는 끔찍한 병목 현상이다.
- **샤딩(Sharding)**: 수백 기가바이트짜리 초거대 모델은 칩 하나에 절대 안 들어가니, 모델 파라미터를 칼로 쪼개듯 썰어서(샤딩) 수백 개의 TPU 칩에 공평하게 뿌려주는 분산 병렬화 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 텍스트나 이미지 입력 텐서 셰이프가 가변으로 들어와 칩이 매번 **가속 선형 대수** 재컴파일을 시도하며 폭주하고 뻗어버리는 지연 현상 | 입력 데이터를 정해진 크기로 **모양 버킷화**하여 고정 패딩하고, 번역 결과를 **컴파일 캐시** 시스템에 강제 저장 및 재사용 적용 | 모델 런타임 런칭 시 수 분이 걸리는 컴파일 지연시간 원천 제거 및 실행 일관성 방어 달성 |
| 구글 칩이 지원 불가한 듣도 보도 못한 신규 연산자 포함에 따른 호스트 우회 **폴백** 발생 및 처참한 성능 병목 지연 | 텐서플로우/JAX 커널 그래프 소프트웨어 뼈대를 칩에 맞게 리팩토링하고 TPU가 알아먹는 대체 호환 연산자로 전환 설계 | 프로세서(CPU-TPU) 간 엄청난 텐서를 톨게이트로 밀어내는 불필요한 데이터 이송 및 통신 병목 원천 차단 |
| 행렬 크기를 잘못 잡아 고속 메모리 대역폭이 꽉 차버리고 수만 개 연산 코어가 손가락 빨고 노는 가동률 추락 참사 | **가속 선형 대수** 연산자 융합 최적화 강제 먹이기 및 타일 크기를 바둑판에 딱 맞게 재조정하여 온칩 텐서 점유율 극한 통제 | 칩 밖으로 안 나가고 칩 내부 온칩 텐서 재사용성을 폭발적으로 증대시켜 끔찍한 메모리 바운드 족쇄 완화 |
| 거대 모델 학습 시 다중 칩 클러스터 간 대규모 파라미터 분산 통신 동기화가 막혀서 전체 포드가 멈춰버리는 병목 현상 | 전용 컴파일러를 통한 모델 **샤딩** 패턴 악착같은 최적화 및 연산기(MXU)의 계산과 인터커넥트 통신의 완벽한 중첩 기법 구현 | 통신이 연산 발목을 잡지 않게 만들어, 칩을 수천 개 꽂아도 선형적으로 빨라지는 대규모 클러스터 스케일아웃 확장 효율성 극대화 |

#### 한줄 요약

- 재컴파일을 막으려면 입력 크기를 고정(버킷화)하고 캐시를 쓰며, 폴백 병목을 피하려면 표준 연산자만 쓰고, 거대 모델은 잘게 썰어(샤딩) 칩 간 통신망(ICI)으로 우아하게 교환한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가속기 아키텍처 선택 기준(Accelerator Architecture Selection Criteria)**: 텐서를 어떤 구조로 처리할지, 데이터센터에 수백 개를 깔아 분산시킬지, 아니면 쿠다 프레임워크 생태계에 묶여있을지를 냉정하게 저울질하여 CPU, GPU, TPU 중 칩의 운명을 결정하는 잣대이다.

</details>

- **가속기 아키텍처 선택 기준**에 따라 수천억 파라미터의 초거대 행렬 및 전용 포드(Pod) 기반 병렬 학습에는 **텐서 처리 장치**, 쿠다 생태계 기반 범용 모델 가속에는 **그래픽 처리 장치** 선택을 단호히 적용함

#### 한줄 요약

- 칩을 하나만 써서 요리조리 연구할 거면 무조건 GPU를 사고, 구글 클라우드에 돈을 쏟아부어 초거대 언어 모델(LLM)을 최단 시간에 끝장낼 거라면 TPU 포드를 임대해야 한다.
