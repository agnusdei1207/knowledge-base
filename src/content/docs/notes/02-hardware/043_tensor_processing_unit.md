## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TPU(Tensor Processing Unit)**: 구글이 딥러닝 텐서 연산 및 행렬 곱셈을 가속하기 위해 자체 개발한 도메인 특화 ASIC.
- **행렬 곱셈 유닛(Matrix Multiply Unit, MXU)**: 2차원 시스톨릭 어레이로 행렬 곱셈·누산을 수행하는 전용 연산기.
- **XLA(Accelerated Linear Algebra)**: 텐서 연산 그래프를 분석하여 연산자를 융합하고 하드웨어 맞춤 기계어로 컴파일하는 가속 엔진.

</details>

- 정의/개념: 행렬 곱셈 전용 **MXU** 및 고대역폭 메모리, 칩 간 전용망을 함께 설계한 도메인 특화 ASIC인 **TPU**
- 배경/필요성: 범용 프로세서 구조로는 **거대 모델 학습 시 메모리 전송 병목 및 집단 통신 지연 극복 불가**

#### 한줄 요약
- TPU는 2차원 시스톨릭 행렬 연산기(MXU)와 칩 간 전용 인터커넥트(ICI)를 하드웨어 레벨에서 통합하여 초거대 모델 분산 학습을 가속한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ICI(Inter-Chip Interconnect)**: TPU 칩들을 직접 연결해 팟(Pod)을 구성하는 전용 칩 간 통신망.

</details>

- MXU 시스톨릭 구조로 중간값을 메모리에 내리지 않고 행렬 곱셈 처리
- **XLA**는 연산 그래프를 융합해 메모리 왕복 제거
- **ICI** 기반 대규모 팟(Pod) 확장성

#### 한줄 요약
- 하드웨어와 XLA 컴파일러가 긴밀히 결합되어 메모리 왕복을 원천 차단하고 수천 개 칩으로 선형적 성능 확장이 가능하다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **벡터 처리 유닛(Vector Processing Unit, VPU)**: 활성화 함수, 정규화(LayerNorm), 소프트맥스 등 벡터 연산을 전담하는 유닛.
- **TPU Pod**: 수천 개의 TPU 칩을 2D/3D 토러스 망으로 결합하여 단일 슈퍼컴퓨터처럼 동작시키는 대규모 클러스터.

</details>

```text
[TPU 코어]
|-- 고대역폭 메모리 (HBM)
|-- 벡터 메모리·DMA 라우터
|-- 연산 유닛
|   |-- MXU (시스톨릭 행렬 곱셈)
|   |-- VPU (활성화·정규화·소프트맥스)
|   `-- 스칼라 유닛 (주소 계산·분기 제어)
`-- ICI 라우터
    `-- TPU Pod (칩 간 2D/3D 토러스 망)
```

선의 의미: 계층 및 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| MXU | 시스톨릭 어레이 구조로 저정밀 **행렬 곱셈**·누산 수행 |
| **VPU** | 활성화·정규화·소프트맥스 등 비선형 벡터 연산 전담 |
| 스칼라 유닛 | 루프 카운팅·주소 계산·분기 제어 실행 |
| 고대역폭 메모리 (HBM) | 대규모 가중치와 활성화 텐서에 고속 **데이터 대역폭** 공급 |
| **ICI** | 호스트를 거치지 않는 칩 간 텐서 교환과 **TPU Pod** 대규모 확장 |

#### 한줄 요약
- TPU는 행렬 연산(MXU), 벡터 연산(VPU), 범용 제어(스칼라) 유닛을 분리 집적하고 ICI 전용망으로 칩 간 통신 지연을 최소화한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연산자 융합(Operator Fusion)**: 여러 개의 작은 연산(곱셈+덧셈+ReLU)을 하나의 통합 커널로 합쳐 HBM 접근을 없애는 최적화.

</details>

```text
JAX·TensorFlow 모델 그래프 정의
        │
   XLA가 그래프 분석 후 연산자 융합
        │
   HBM에서 가중치를 MXU에 적재하고 입력 주입
        │
   MXU 누산 결과에 VPU가 활성화·정규화 적용
        │
   단일 칩으로 끝나는가?
   ┌────┴─────┐
  예           아니오 (분산 학습)
   │             │
결과 반환      ICI로 기울기 All-Reduce 동기화
   │             │
   └────┬────────┘
        │
   다음 스텝 진행
```

#### 한줄 요약
- XLA가 텐서 연산자를 하나로 융합 컴파일하여 HBM 접근을 줄이고, 분산 학습 시 ICI 전용 통신망을 통해 초고속 All-Reduce를 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **온디바이스 NPU**: 모바일·엣지 디바이스에서 저전력 실시간 딥러닝 추론을 전담하는 신경망 처리 장치.
- **NVIDIA GPU**: 범용 SIMT 코어와 Tensor 코어를 바탕으로 AI 학습/추론 및 그래픽을 폭넓게 가속하는 프로세서.

</details>

| AI 가속 프로세서 | Google TPU | NVIDIA GPU | 온디바이스 NPU | 범용 CPU |
|:---|:---|:---|:---|:---|
| 적용 기준 | 구글 클라우드 기반 초대형 LLM 학습/추론 | 범용 AI 프레임워크 및 다양한 HPC 가속 | 모바일·임베디드 초저전력 실시간 추론 | 범용 연산 및 복잡한 제어 중심 태스크 |
| 핵심 특징 | 대규모 MXU 시스톨릭 어레이 및 ICI Pod 확장 | 범용 SIMT 코어 및 방대한 CUDA 생태계 | 극저전력 NPU 코어 및 SoC 온칩 집적 | 직렬 명령어 고속 디코딩 및 다단계 캐시 |
| 한계 | 구글 클라우드 환경 종속성·타 프레임워크 제약 | 높은 소비 전력 및 분산 통신 인프라 비용 | 온칩 SRAM 용량 한계로 거대 모델 구동 불가 | 텐서 병렬 연산 대역폭 절대 부족 |

#### 한줄 요약
- 초대규모 AI 분산 학습에는 전용망을 갖춘 TPU Pod가 유리하며, 범용 모델 개발 및 이종 환경 배포에는 GPU 생태계가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **bfloat16**: FP32와 동일한 지수부(8비트)를 유지하여 오버플로 없이 가수부를 7비트로 줄여 행렬 곱셈을 가속하는 부동소수점 포맷.
- **형상 버킷팅(Shape Bucketing)**: 가변 입력 길이를 사전 정의된 고정 크기 버킷으로 패딩하여 XLA의 잦은 재컴파일 오버헤드를 방지하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 입력 길이에 따른 XLA 재컴파일 지연 | **형상 버킷팅** 기반 고정 크기 패딩 적용 | 컴파일 형태 수 축소 및 실행 지연 안정화 |
| 거대 모델 분산 학습에서 칩 간 통신 병목 | ICI 3D 토러스 토폴로지 맞춤형 텐서 병렬화 | 연산과 집단 통신 간 대역폭 불균형 해소 |
| FP32 연산으로 인한 HBM 대역폭 낭비 | **bfloat16** 혼합 정밀도 및 손실 스케일링 | 정확도 손실 없는 데이터 전송량 50% 절감 |
| 비표준 연산자 발생 시 CPU 호스트 폴백 | XLA 표준 프리미티브 재구성 또는 커스텀 Pallas 커널 작성 | 호스트-디바이스 전환 오버헤드 방지 |

#### 한줄 요약
- TPU 실무 운용 시 XLA의 정적 형상 요구조건에 맞춘 버킷팅 처리와 bfloat16 혼합 정밀도 적용이 핵심 성능 요소다.

## Ⅶ. 결론

- XLA 최적화가 가능하고 초거대 클러스터 확장이 필수적인 워크로드는 **TPU Pod**를 도입하고, 커스텀 연산 비중이 높거나 멀티 클라우드가 요구되면 **GPU 생태계** 채택

#### 한줄 요약
- TPU 채택의 핵심 기준은 XLA 그래프 컴파일 수용성과 ICI 기반의 대규모 분산 확장 효율성이다.
