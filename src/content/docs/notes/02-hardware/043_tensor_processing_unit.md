## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **TPU(Tensor Processing Unit)**: 구글이 텐서플로(TensorFlow)/JAX 프레임워크 및 대규모 딥러닝 연산에 최적화하여 독자 개발한 AI 도메인 특화 가속 프로세서(DSA ASIC).
- **시스톨릭 어레이(Systolic Array)**: 데이터가 프로세서 내부 격자형 연산 셀들을 심장 박동(Systole)처럼 주기적으로 흘러가며 레지스터 접근 없이 연산을 누산하는 하드웨어 구조.

</details>

- 정의/개념: 구글이 대규모 딥러닝 텐서 연산을 초고속으로 처리하기 위해 2D 시스톨릭 어레이와 전용 인터커넥트를 통합 설계한 **도메인 특화 AI 가속 ASIC 프로세서**
- 배경/필요성: 행렬 곱셈(GEMM) 수행 시 빈번한 외부 메모리 왕복으로 인한 **데이터 이동 전력 낭비와 칩 간 통신 병목에 따른 대규모 분산 학습 확장 한계 극복 필요성 증대**

#### 한줄 요약
- TPU는 2D 시스톨릭 행렬곱 연산기(MXU)와 대용량 SRAM 버퍼를 결합하여 행렬 연산 처리량과 전력 효율을 극대화한 구글의 AI 전용 칩이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **MXU(Matrix Multiply Unit)**: TPU의 핵심 연산 엔진으로, 수만 개의 곱셈 누산기(MAC)가 2차원 격자로 배열되어 bfloat16 행렬 곱을 1클록에 처리하는 시스톨릭 어레이.
- **bfloat16 (Brain Floating Point)**: FP32와 동일한 지수부(8비트)를 유지하고 가수부를 7비트로 축소하여 FP32의 동적 범위를 보존하면서 대역폭을 절반으로 줄인 16비트 포맷.
- **ICI(Inter-Chip Interconnect)**: 호스트 CPU나 외부 네트워크 스위치를 거치지 않고 TPU 칩 간을 직접 고속 연결하는 구글 전용 광학/전기 인터커넥트.

</details>

- 2차원 격자 구조의 **시스톨릭 행렬곱 연산기(MXU)**를 통해 셀 간 직접 데이터 전파로 레지스터 및 메모리 접근 90% 이상 절감
- **XLA 전용 컴파일러** 기반의 연산자 융합(Operator Fusion)을 통해 중간 결과의 HBM 입출력을 온칩 파이프라인으로 흡수
- 호스트 CPU 개입 없는 독자적 **칩 간 직접 상호연결망(ICI: Inter-Chip Interconnect)**을 구축하여 수천 개 칩의 선형적 3D 토러스 확장 보장

#### 한줄 요약
- MXU 시스톨릭 어레이와 XLA 컴파일러 융합, ICI 전용 토러스 네트워크를 통해 수천 칩의 선형적 확장을 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **벡터 처리 유닛(Vector Processing Unit, VPU)**: 활성화 함수(GELU, ReLU), 레이어 정규화(LayerNorm), 소프트맥스 등 벡터 연산을 전담하는 SIMD 유닛.
- **TPU Pod**: 수천 개의 TPU 칩을 ICI 초고속 광학 토러스 망으로 결합하여 엑사플롭스(ExaFLOPS)급 연산력을 제공하는 대규모 클러스터 시스템.

</details>

```text
[Google TPU 코어 아키텍처]
  │
  ├─ [온칩 텐서 메모리 계층] (SRAM Buffer)
  │     ├─ [벡터 메모리] (VMem, 활성화 텐서 타일 버퍼)
  │     └─ [가중치 메모리] (WMem, 가중치 고속 공급 버퍼)
  │
  ├─ [2D 시스톨릭 행렬곱 엔진] (MXU)
  │     ├─ [128x128 bfloat16 MAC 격자망] (인접 셀 간 직접 전파)
  │     └─ [부분합 누적 레지스터] (행렬곱 출력 파이프라인)
  │
  ├─ [벡터 처리 유닛] (VPU)
  │     ├─ [비선형 활성화 파이프라인] (GELU, ReLU 연산)
  │     └─ [정규화 & 감량 엔진] (LayerNorm, Softmax 벡터화)
  │
  ├─ [제어 및 통신 인터페이스] (스칼라 유닛 및 ICI)
  │     ├─ [스칼라 프로세서] (루프 제어 및 주소 계산 DMA)
  │     └─ [칩 간 인터커넥트 라우터] (ICI, 3D 토러스 직결)
  │
  └─ [외부 고대역폭 메모리] (HBM3E 서브시스템)
```

선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 행렬 곱셈 유닛 (MXU) | 2차원 시스톨릭 어레이 격자망을 통해 **bfloat16 대규모 행렬곱을 1클록 스트리밍 가속** |
| 벡터 처리 유닛 (VPU) | 초광폭 SIMD 파이프라인으로 **GELU, LayerNorm, Softmax 등 비선형 활성화 연산 전담** |
| 온칩 메모리 (VMem/WMem) | 테라바이트급 초저지연 온칩 SRAM 버퍼로 **외부 HBM 트래픽 차단 및 텐서 타일링 제공** |
| 칩 간 인터커넥트 (ICI) | 호스트 경유 없이 TPU 칩 간을 3D 토러스 광학망으로 직결하여 **선형적 분산 확장 보장** |

#### 한줄 요약
- MXU가 시스톨릭 셀 사이로 데이터를 흘려 곱셈마다 되풀이되던 메모리 재접근을 없애고, 활성화·정규화 같은 비선형 연산은 VPU가, 주소 계산과 분기는 경량 스칼라 유닛이 떼어 맡아 MXU를 행렬곱 전용으로 비워 둔다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **연산자 융합(Operator Fusion)**: 여러 개의 개별 연산(MatMul + Bias + GELU)을 하나의 통합 하드웨어 루프로 결합하여 HBM 메모리 접근을 없애는 최적화.

</details>

```text
+-------------------------------------------------------------+
|          AI 모델 연산 그래프 정의 및 컴파일러 입력           |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       1. XLA 컴파일러의 연산 그래프 분석 및 인라인 연산자 융합|
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       2. 가중치 텐서의 온칩 WMem 캐싱 및 MXU 셀 프리로드     |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       3. MXU 2D 시스톨릭 어레이 기반 스트리밍 행렬곱 연산    |
+-------------------------------------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|       4. VPU의 비선형 활성화 함수 및 정규화 연속 적용        |
+-------------------------------------------------------------+
                               |
                               v
               +-------------------------------+
               |     5. 분산 학습 동기화 판정  |
               +-------------------------------+
                      |                 |
             [단일 칩 로컬 추론]        | [TPU Pod 분산 학습]
                      |                 v
                      | +-------------------------------+
                      | | ICI 전용 3D 토러스 라우터를   |
                      | | 통한 실시간 All-Reduce 동기화 |
                      | +-------------------------------+
                      v                 |
+-----------------------+               |
| 호스트로 최종 결과 반환|               |
+-----------------------+               |
                      |                 |
                      +--------+--------+
                               v
+-------------------------------------------------------------+
|          최종 텐서 연산 완료 및 다음 학습/추론 스텝 진행      |
+-------------------------------------------------------------+
```

분기 결과: **단일 칩 추론**은 온칩 파이프라인 완료 즉시 호스트로 반환되나, **TPU Pod 분산 환경**에서는 ICI 전용망을 통해 호스트 개입 없는 실시간 All-Reduce 그래디언트 동기화가 병렬 수행됨

**동작 원리**

1. **XLA 연산자 융합**: 구글 XLA 컴파일러가 모델 그래프를 분석하여 행렬곱, 바이어스 가산, 활성화 함수를 단일 하드웨어 루프로 통합 융합
2. **가중치 온칩 프리로드**: 컴파일된 실행 바이너리가 가중치 텐서를 온칩 WMem에 적재하고 MXU 내부 시스톨릭 레지스터에 선제 고정
3. **2D 시스톨릭 스트리밍 계산**: 활성화 데이터가 클록마다 가로축으로 인접 셀에 전파되며, MAC 셀이 누적 연산된 부분 합을 세로축 아래 셀로 연속 방출
4. **VPU 파이프라인 인라인 실행**: MXU에서 출력된 원시 행렬 데이터가 외부 메모리를 거치지 않고 VPU로 직결되어 GELU 비선형 함수 및 LayerNorm을 1사이클 내에 완수
5. **ICI 기반 고속 분산 동기화**: 분산 학습 시 각 칩의 연산 결과가 전용 ICI 라우터를 통해 이웃 노드로 직접 전달되며 3D 토러스 토폴로지 상에서 손실 없이 All-Reduce 합산

#### 한줄 요약
- 연산자 융합은 레이어마다 반복되던 HBM 왕복을 온칩 루프 하나로 접고, 칩 간 그래디언트 동기화는 ICI가 대신 맡아 규모를 키워도 통신이 확장의 상한이 되지 않게 한다.

## Ⅴ. 종류 및 비교

| 대상 구분 | Google TPU (v4 / v5p) | NVIDIA GPU (H100 / B200) | 온디바이스 NPU | 범용 CPU (x86_64) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 초대규모 클라우드 LLM 분산 학습 및 팟 전용 서빙 시 | 전 세계 범용 AI 연구, 다양한 모델 구조 및 유연한 분산 환경 구축 시 | 스마트폰 및 엣지 IoT 기기 내 밀리와트급 실시간 추론 시 | 복잡한 제어 흐름, 전처리 및 범용 비즈니스 로직 시 |
| 핵심 특징 | 대규모 **2D 시스톨릭 어레이 (MXU)**, XLA 컴파일러, **ICI 전용 3D 토러스 광학망** 직결 | 다중 코어 **SIMT SM**, NVLink/NVSwitch 및 독점적 CUDA/cuDNN 생태계 주도 | 초저전력 정수형 MAC 어레이, 온칩 SRAM 최적화, TFLite/ONNX 경량 런타임 | 범용 비순차 슈퍼스칼라 코어, 대용량 L3 캐시, 표준 C/C++ 및 OpenMP 실행 |
| 한계 | 구글 클라우드 종속성, 비정형 모델 커스텀 연산 유연성 제한 | 고전력 소모(TDP 700W+), 초고가 도입 비용 및 단일 벤더 종속 심화 | 가변 시퀀스 및 대규모 부동소수점 학습 불가, 온칩 메모리 용량 제약 | 초병렬 대규모 행렬곱 대역폭 부족, AI 연산 시 전력 대비 성능 극저하 |

#### 한줄 요약
- 구글 클라우드 기반 초대규모 분산 학습에는 TPU가 최강의 가성비를 내며, 범용 생태계와 다양한 연구에는 GPU가 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **형상 버킷팅(Shape Bucketing)**: 가변 길이 텍스트 입력을 사전에 정의된 몇 개의 고정 크기(128, 512, 2048 등)로 패딩하여 XLA 컴파일러의 잦은 재컴파일을 방지하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가변 텍스트 길이에 따른 XLA 컴파일러의 잦은 재컴파일 | **형상 버킷팅(Shape Bucketing)** 및 고정 크기 패딩 | 재컴파일 지연 원천 제거 및 실행 일관성 확보 |
| 수천 노드 초대규모 분산 학습 시 칩 간 통신 정체 발생 | **ICI 토러스 맞춤형 SPMD** 샤딩 분할 | 대규모 클러스터 팟 확장 효율 95% 이상 유지 |
| 단정밀도(FP32) 적용 시 HBM 메모리 대역폭 조기 고갈 | **bfloat16 혼합 정밀도** 및 동적 손실 스케일링 | 연산 처리량 2배 향상 및 메모리 사용량 절반 절감 |

#### 한줄 요약
- 실무에서는 형상 버킷팅으로 재컴파일을 막고, ICI 맞춤 병렬화로 통신 병목을 없애며, bfloat16으로 대역폭을 최적화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **광학 회로 스위치(Optical Circuit Switch, OCS)**: TPU Pod 네트워크에서 광섬유 경로를 MEMS 거울로 동적 전환하여 패킷 라우터 오버헤드 없이 초저지연 광경로를 제공하는 광학 스위칭 기술.
- **총소유비용(Total Cost of Ownership, TCO)**: 하드웨어 도입비, 전력 인프라, 냉각 및 상면 비용을 종합적으로 포괄한 수명 주기 총비용.

</details>

- **광학 패브릭 및 팟 토폴로지 진화**: 광학 회로 스위치(Optical Circuit Switch, OCS) 기반의 무손실 동적 토폴로지 재구성과 초고속 칩간 인터커넥트(ICI)를 융합한 차세대 엑사스케일 TPU Pod 클러스터링 고도화 추세.
- **분산 병렬화 및 TCO 최적화 통찰**: 텐서·파이프라인 분산 모델 및 XLA 정적 컴파일러 특성을 심층 분석하여, 범용 GPU 대비 총소유비용(Total Cost of Ownership, TCO)과 전력 효율을 극대화하는 아키텍처 선별 기준 수립 필요.

#### 한줄 요약
- OCS 광학 스위칭과 ICI 패브릭 기반 TPU Pod로 확장되고 있으며, XLA 컴파일러 특성과 워크로드 분산 패턴을 고려한 TCO 기반 아키텍처 선정이 핵심이다.
