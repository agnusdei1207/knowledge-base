## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 흐름 컴퓨터(Dataflow Computer)**: 명령의 실행 순서를 결정하는 프로그램 카운터(PC) 없이, 입력 데이터(Token)가 모두 준비(Ready)되는 즉시 연산을 비순서(Out-of-Order)로 발화 실행하는 비폰노이만 컴퓨터 아키텍처.
- **토큰(Token)**: 데이터 값(Value), 연산자의 목적지 노드 주소(Tag/Address) 및 콘텍스트 정보를 보유하는 전송 단위.
- **발화(Firing)**: 연산 노드가 요구하는 모든 입력 토큰이 도착했을 때 해당 연산자(ALU)가 구동되는 즉각적 실행 조건.

</details>

- 정의/개념: 프로그램 카운터(PC) 제어 방식 대신, **토큰**이 모든 필수 노드에 수용되었을 때 노드를 **발화**시키는 **데이터 흐름 컴퓨터**
- 배경/필요성: 순차적 PC 스케줄링 기반 폰 노이만 병목(Von Neumann Bottleneck) 및 메모리 대기 지연 극복 요구성

#### 한줄 요약

- 데이터 흐름 컴퓨터는 명령 순서가 아니라 토큰의 준비 여부를 기준으로 연산을 실행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 흐름 그래프(Dataflow Graph)**: 프로그램을 연산 노드와 데이터 의존 에지로 표현한 유향 그래프.
- **태그(Tag)**: 루프 반복, 함수 재귀 호출 시 복수의 데이터 토큰을 물리 노드 상에서 구별 짓는 식별자 메타데이터.
- **토큰 매칭(Token Matching)**: 2개 이상의 피연산자 토큰이 짝을 이루어 동일 노드에 도착했는지 matching unit이 비동기 판정하는 메커니즘.

</details>

- 제어 흐름(PC)이 전무하고 데이터 가용성에 근거하여 비동기 실행되는 **데이터 흐름 그래프** 기반 연산
- 루프 및 재귀 호출 간 토큰 엉킴을 막기 위한 식별용 **태그** 도입
- 데이터 의존성이 허용하는 **암묵적 병렬성** 노출

#### 한줄 요약

- 독립 연산 병렬성과 토큰 매칭·이동 비용 사이에는 상충 관계가 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **토큰 매칭 저장소(Matching Unit/Store)**: 수신된 토큰의 태그를 비교 검색하여 2-operand 발화 조건이 완성되었는지 판정하는 검색 저장소.
- **실행 유닛(Processing Element/ALU)**: 준비 노드의 산술/논리 연산을 수행하고 결과값에 타깃 태그를 부가하여 출력 토큰을 생성하는 연산기.

- **처리 요소(Processing Element, PE)**: 데이터플로우 아키텍처에서 모든 입력 토큰이 매칭되었을 때 독립적으로 연산을 수행하는 단위 프로세싱 노드.
</details>

```text
데이터 흐름 컴퓨터
├─ 데이터 흐름 그래프
├─ 토큰 매칭 저장소
├─ 준비 노드 스케줄러
├─ 실행 유닛
└─ 출력 계층
```

선의 의미: 데이터 흐름 그래프를 바탕으로 토큰 매칭 저장소, 준비 노드 스케줄러, 실행 유닛 및 출력 계층이 비동기 연계되는 파이프라인.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 흐름 그래프 | 프로그램 노드 간 데이터 의존성(DAG) 인코딩 |
| 토큰 매칭 저장소 | 태그 기반 필수 피연산자 **토큰 매칭**과 결합 판정 |
| 준비 노드 스케줄러 | 입력이 완비된 노드를 연산 코어(**PE**)로 디스패치 |
| 실행 유닛 | 산술/논리 연산 수행 및 결과 **토큰** 바인딩 |
| 출력 계층 | 최종 결과 시퀀싱 및 외부 메모리/인터페이스 래칭 |

#### 한줄 요약

- 데이터 흐름 그래프·토큰 매칭 저장소·준비 노드 스케줄러·실행 유닛·출력 계층이 실행 구조를 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **준비 노드(Ready Node)**: 연산에 필요한 모든 피연산자 토큰이 도착한 상태.
- **결과 토큰(Result Token)**: ALU 실행 결과값에 후속 노드 매핑 태그를 결합한 전송 객체.

</details>

```text
[입력 토큰]
      │
      ▼
┌────── 실행 가능 노드가 남는 동안 ──────┐
│ 1. 토큰 매칭•준비 판정                 │
│              │                         │
│              ▼                         │
│ 2. 준비 연산 병렬 발행                 │
│              │                         │
│              ▼                         │
│ 3. 결과 토큰 생성•전달                 │
│              │                         │
│              └── 후속 노드 입력으로 반복
└────────────────────────────────────────┘
      │
      ▼
[최종 결과 정렬]
```

### 동작 원리

1. **토큰 매칭·준비 판정**: 유입된 **토큰**의 태그를 비교해 모든 필수 피연산자의 도착 판정.
2. **준비 연산 병렬 발행**: **준비 노드**를 가용 **실행 유닛**에 병렬 디스패치.
3. **결과 토큰 생성·전달**: 연산 수행 및 후속 노드 태그가 포함된 **결과 토큰**을 생성하여 버스로 방출.

#### 한줄 요약

- 준비 노드는 연산 발행으로 실행하고, 의존 노드는 필요한 결과 토큰이 도착할 때까지 기다린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **제어 흐름 컴퓨터(Control-Flow Computer)**: PC(Program Counter)에 의해서 순차적으로 명령어가 메모리에서 Fetch되어 수행되는 전통 폰노이만 컴퓨팅.

</details>

| 비교 항목 | 데이터 흐름 컴퓨터 (Dataflow) | 제어 흐름 컴퓨터 (Control-Flow) |
|:---|:---|:---|
| 동기화 기준 | 데이터 수용 여부 (**토큰 매칭** 시 발화) | 명령어 주소 순서 (**Program Counter**) |
| 병렬성 수용 | 데이터 의존성이 허용하는 **암묵적 병렬성** | 컴파일러·명령어 수준 병렬성 제어 |
| 주요 한계 | **토큰 매칭 저장소** 매칭 오버헤드, 태그 메모리 팽창 | 폰 노이만 병목, 메모리 접근 대기 지연 |

#### 한줄 요약

- 데이터 흐름 컴퓨터는 피연산자 준비 상태, 제어 흐름 컴퓨터는 프로그램 카운터와 분기 결과로 다음 실행을 결정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **백프레셔(Backpressure)**: 매칭 버퍼 팽창 시 상류 토큰 생성을 비동기 억제하는 흐름 제어.
- **연산 입도(Coarse-Grained Granularity)**: 1개 토큰 당 단순 산술 연산 대신 대용량 텐서/블록 연산을 할당하여 토큰 매칭 오버헤드를 대폭 줄이는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Fine-Grained 연산 시 **토큰 매칭** 오버헤드 극증 | 대용량 텐서 단위 **연산 입도** 전환 | 매칭 유닛 로드 하락 |
| 루프 및 재귀 호출 폭증 시 태그 메모리 오버플로우 | **백프레셔** 및 토큰 생성 속도 피드백 제어 | 토큰 저장소 팽창 방지 |
| 전송 노드 간 토큰 이동 지연 발생 | 공간적 **지역성 기반 배치** | 네트워크 호핑 지연 단축 |

> 사례: AI 딥러닝 텐서 처리용 **Coarse-Grained Dataflow** 아키텍처(CGRA, TPU 등) 수용

#### 한줄 요약

- 토큰 수명과 연산 입도 및 지역성 기반 배치를 조정하여 태그 저장과 토큰 통신 부담을 줄인다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실행 구조 선택 기준(Execution Architecture Selection Criteria)**: 알고리즘의 데이터 의존성 분산도 및 토큰 오버헤드 감당성에 따른 아키텍처 채택 지표.

</details>

- **실행 구조 선택 기준**에 따라 차세대 AI 텐서 그래프 처리는 **Coarse-Grained 데이터 흐름 컴퓨터**, 순차 제어는 **제어 흐름 컴퓨터** 채택

#### 한줄 요약

- 규칙적 데이터 의존 그래프는 데이터 흐름, 분기 중심 순차 제어는 제어 흐름을 선택한다.
