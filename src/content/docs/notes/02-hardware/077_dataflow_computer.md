## 미리 알고가기

- **데이터 흐름 컴퓨터(Dataflow Computer)**: 필요한 피연산자가 준비된 연산부터 실행하는 컴퓨터 구조
- **제어 흐름 컴퓨터(Control-flow Computer)**: 프로그램 카운터와 분기 결과로 다음 명령을 정하는 구조
- **데이터 흐름 그래프(Dataflow Graph)**: 연산을 노드, 값의 의존 관계를 방향 간선으로 나타낸 표현
- **토큰(Token)**: 연산값과 실행 문맥을 함께 전달하는 단위
- **태그(Tag)**: 목적 노드·입력 위치·실행 인스턴스를 구분하는 식별자
- **발화(Firing)**: 모든 입력 토큰이 모인 노드를 실행하는 동작
- **토큰 매칭(Token Matching)**: 같은 연산 인스턴스에 속한 입력 토큰을 결합하는 처리
- **실행 유닛(Execution Unit)**: 발화된 산술·논리 연산을 수행하고 결과 토큰을 만드는 장치
- **제어 의존성(Control Dependency)**: 분기 결과에 따라 후속 연산 실행 여부가 정해지는 관계
- **동적 데이터 흐름(Dynamic Dataflow)**: 태그로 반복·재귀의 여러 실행 인스턴스를 구별하는 방식

## Ⅰ. 개요

- 정의/개념: 피연산자 토큰이 모두 도착한 노드를 **준비 순서대로 발화**하는 병렬 구조
- 기존 한계: 프로그램 카운터 중심 순차 발행은 독립 연산이 준비돼도 제어 순서에 묶일 수 있음

### 쉽게 이해하기 (학습용)

- 주문 순서가 아니라 재료가 모두 모인 요리부터 만든다.

## Ⅱ. 특징

- 데이터 의존성이 없는 노드는 자연스럽게 동시 실행
- 태그·토큰으로 반복과 여러 실행 문맥 구분
- 토큰 매칭·저장·이동 비용이 확장성과 효율 제한

### 쉽게 이해하기 (학습용)

- 병렬성은 쉽게 드러나지만 재료표를 분류하고 옮기는 비용이 든다.

## Ⅲ. 아키텍처 및 구성요소

### 도표안 A. 데이터 흐름 실행 엔진 정적 구조

```mermaid
flowchart LR
    I[입력 토큰] --> M[토큰 매칭 저장소]
    G[데이터 흐름 그래프] --> S[준비 노드 스케줄러]
    M -->|피연산자 집합| S
    S -->|발화 연산| E[실행 유닛]
    E -->|결과 토큰| M
    E -->|최종 값| O[출력]
```

| 설계 요소 | 입력·상태 | 역할 |
|:---|:---|:---|
| 데이터 흐름 그래프 | 연산·의존 간선 | 연산과 토큰 목적지 정의 |
| 토큰 매칭 저장소 | 값·태그·입력 위치 | 같은 노드의 피연산자 결합 |
| 준비 노드 스케줄러 | 완성된 피연산자 집합 | 실행 가능한 연산 선택·발행 |
| 실행 유닛 | 연산 코드·피연산자 | 계산 후 결과 토큰 생성 |
| 출력 계층 | 종료 노드 결과 | 실행 결과 정렬·외부 전달 |

> 요약: 토큰 매칭이 준비된 노드를 발화하고 결과를 다시 전파

### 쉽게 이해하기 (학습용)

- 분류대가 재료를 한 묶음으로 모으면 작업대가 계산하고 다음 분류대로 보낸다.

### 도표안 B. 토큰 매칭·병렬 발화 시퀀스

```mermaid
sequenceDiagram
    participant G as 데이터 흐름 그래프
    participant I as 입력 계층
    participant M as 토큰 매칭 저장소
    participant S as 준비 노드 스케줄러
    participant E1 as 실행 유닛 1
    participant E2 as 실행 유닛 2
    participant E3 as 실행 유닛 3
    participant O as 출력 계층

    G->>M: ① 노드 입력 위치·결과 라우팅 규칙 적재
    I->>M: ② 값·목적 노드·입력 위치·문맥 태그 전달
    M->>S: ③ 피연산자가 완성된 노드 A 통지
    M->>S: ④ 피연산자가 완성된 노드 B 통지
    par 의존성이 없는 노드
        S->>E1: ⑤ 노드 A 발화·피연산자 전달
        S->>E2: ⑥ 노드 B 발화·피연산자 전달
    end
    E1->>M: ⑦ A 결과 토큰·문맥 태그 반환
    E2->>M: ⑧ B 결과 토큰·문맥 태그 반환
    M->>S: ⑨ 같은 문맥의 결합 노드 C 준비 통지
    S->>E3: ⑩ 노드 C 발화·두 결과 전달
    E3->>O: ⑪ 종료 노드 결과 전달
```

#### 동작 원리

1. **그래프 적재**: 데이터 흐름 그래프가 각 노드의 입력 위치와 결과 토큰의 목적지 규칙을 매칭 저장소에 적재한다.
2. **입력 토큰 수신**: 입력 계층이 값과 함께 목적 노드·입력 위치·실행 문맥 태그를 전달한다.
3. **노드 A 준비**: 저장소가 같은 문맥의 필수 피연산자를 모두 모으면 노드 A가 실행 가능하다고 알린다.
4. **노드 B 준비**: A와 데이터 의존성이 없는 노드 B도 피연산자가 모이는 즉시 별도로 준비 상태가 된다.
5. **노드 A 발화**: 스케줄러가 가용 실행 유닛 1에 A의 연산 코드와 피연산자를 발행한다.
6. **노드 B 병렬 발화**: 스케줄러가 실행 유닛 2에 B를 동시에 발행해 명시적 프로그램 순서 없이 병렬 실행한다.
7. **A 결과 전파**: 실행 유닛 1이 결과값에 목적지와 원래 문맥 태그를 붙여 매칭 저장소로 돌려보낸다.
8. **B 결과 전파**: 실행 유닛 2도 같은 방식으로 B 결과 토큰을 저장소에 반환한다.
9. **결합 노드 준비**: 저장소가 동일 실행 문맥의 A·B 결과를 모두 모아 후속 노드 C의 준비를 알린다.
10. **결합 연산 발화**: 스케줄러가 노드 C와 두 피연산자를 실행 유닛 3에 발행한다.
11. **최종 결과 전달**: 종료 노드의 결과는 추가 목적 노드 대신 출력 계층으로 전달해 외부 순서와 형식에 맞춘다.

### 쉽게 이해하기 (학습용)

- 서로 상관없는 두 계산은 재료가 모이는 즉시 동시에 실행하고, 두 결과가 모두 모여야 합치는 계산을 시작한다.

## Ⅳ. 종류 및 비교

| 판단 기준 | 데이터 흐름 구조 | 제어 흐름 구조 |
|:---|:---|:---|
| 실행 결정 | 입력 토큰 충족 | 프로그램 카운터·분기 |
| 강점 | 의존성 기반 병렬성 노출 | 단순한 순서·상태 관리 |
| 한계 | 매칭·통신·태그 비용 | 제어·메모리 의존 병목 |

> 요약: 데이터 흐름은 값의 준비 상태, 제어 흐름은 명령 순서로 실행 결정

### 쉽게 이해하기 (학습용)

- 하나는 재료가 모이면 시작하고 다른 하나는 번호표 순서대로 시작한다.

## Ⅴ. 실무 고려사항 및 대응 방안

| 운영 위험 | 대응 | 기대 효과 |
|:---|:---|:---|
| 태그·토큰 저장소 용량 초과 | 실행 문맥 제한과 토큰 수명·백프레셔 관리 | 교착·메모리 폭증 방지 |
| 매칭·스케줄링 비용이 연산 이득 상쇄 | 굵은 연산 단위와 지역 매칭·배치 발행 | 제어 오버헤드 축소 |
| 원거리 토큰 이동으로 네트워크 병목 | 생산자·소비자 배치와 지역성 기반 라우팅 | 통신 지연·전력 감소 |
| 부작용·입출력 순서가 비결정적 | 효과 토큰·순서 제약과 재현 가능한 추적 | 정확성·디버깅 가능성 확보 |

### 쉽게 이해하기 (학습용)

- 계산이 빨라도 토큰이 쌓이거나 멀리 이동하면 전체는 느려진다.

### 적용 사례

- 신경망 가속기는 연산 그래프의 입력 타일이 준비된 연산부터 실행 유닛에 배치하고 생산자·소비자를 가깝게 두어 중간 텐서 이동을 줄인다.

### 쉽게 이해하기 (학습용)

- 필요한 값이 가까이 있는 계산부터 가속기 작업대에 보낸다.

## Ⅵ. 결론

- 데이터 의존 병렬성을 활용하기 위해 **준비 노드 수·연산 입도·토큰 매칭 비용·통신 지역성·부작용 순서**를 검토하고, 병렬 이득이 런타임 비용을 넘는 워크로드에 적용한다.

### 쉽게 이해하기 (학습용)

- 동시에 할 계산이 충분하고 토큰 관리가 가벼울 때 효과적이다.
