## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터플로우 컴퓨터(Dataflow Computer)**: 프로그램 카운터(PC)의 순차적 명령 인출 방식 대신, 연산에 필요한 입력 데이터(토큰)가 모두 준비되는 즉시 해당 명령 노드를 병렬 실행하는 비-폰노이만 컴퓨팅 아키텍처.
- **발화 규칙(Firing Rule)**: 데이터플로우 그래프 상의 연산 노드가 모든 입력 포트에 유효한 피연산자 토큰을 수신했을 때 실행 큐로 자동 투입되는 하드웨어 트리거 조건.

</details>

- 정의/개념: 프로그램 카운터 없이 데이터 가용성에 의해 연산이 자율 트리거되는 **데이터플로우 컴퓨터** 아키텍처
- 배경/필요성: 전통 폰 노이만 구조의 순차 제어로 인한 명령어 인출·디코딩 오버헤드 및 메모리 벽(Memory Wall) 병목 한계

#### 한줄 요약
- 데이터플로우 컴퓨터는 명령 순서가 아닌 데이터 의존성에 따라 연산을 실행하여 알고리즘 내재 병렬성을 하드웨어적으로 극대화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 토큰(Data Token)**: 데이터플로우 그래프 상에서 연산 노드로 전달되는 데이터 값과 목적지 노드 ID, 컨텍스트 태그(Tag)가 캡슐화된 기본 전송 패킷.
- **암묵적 병렬성(Implicit Parallelism)**: 프로그래머가 복잡한 멀티스레딩이나 동기화 락을 작성하지 않아도, 데이터 간 의존성이 없는 독립 경로들이 하드웨어에 의해 완전 자동으로 동시 실행되는 특성.

</details>

- 데이터 구동 발화: 모든 입력 토큰 도착 시 즉각 연산이 시작되는 **발화 규칙(Firing Rule)** 기반 자율 구동
- **암묵적 병렬성**: 컴파일러가 생성한 데이터 의존성 그래프(DFG) 기반 하드웨어 자동 병렬 가동
- 동적 태그 매칭: 루프와 함수 인스턴스 동시 처리를 위해 토큰에 컨텍스트 태그를 부착하여 연관 메모리에서 매칭

#### 한줄 요약
- 토큰 매칭 기반 발화 규칙을 통해 순차 제어 오버헤드 없이 고유의 병렬성을 하드웨어 공간에서 직접 추출한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **매칭 메모리 유닛(Matching Unit)**: 연산 노드의 모든 입력 피연산자 토큰이 도착했는지 연관 메모리(CAM)를 통해 태그와 목적지 ID를 대조하는 하드웨어 블록.
- **처리 요소 어레이(Processing Element Array, PE Array)**: 산술·논리 연산기(ALU/MAC)와 로컬 레지스터를 내장하고 발화된 명령을 실행하는 2D 그리드 연산 코어망.

</details>

```text
[데이터플로우 프로세서 아키텍처]
├── 온칩 토큰 라우팅 NoC: 2D 메시 기반 결과 토큰 패킷 전달망
├── 매칭 메모리 유닛 (Matching Unit): CAM 기반 토큰 태그 매칭
├── 노드 메모리 (Node Memory): DFG 템플릿 및 연산 코드(Opcode) 저장
├── 실행 준비 큐 (Ready Queue): 발화 조건 충족 노드 대기 버퍼
└── 처리 요소 어레이 (PE Array): 2D 다중 ALU/MAC 연산 코어망
```

선의 의미: 가지(`├──`, `└──`)는 하드웨어 소속 및 토큰 순환 파이프라인 구성; 토큰이 매칭 유닛에서 충족되면 PE 어레이에서 연산 후 결과 토큰을 NoC로 송출함

| 구성요소 | 책임 |
|:---|:---|
| **매칭 메모리 유닛** | 태그 기반 피연산자 매칭 |
| 노드 메모리 | 연산·목적지 DFG 템플릿 저장 |
| 실행 준비 큐 | 발화 노드의 PE 디스패치 |
| 처리 요소 | 연산 실행과 결과 토큰 생성 |
| 토큰 라우팅 NoC | 후속 노드로 패킷 라우팅 |

#### 한줄 요약
- 노드 메모리가 연산과 함께 결과를 보낼 목적지까지 들고 있어 다음에 실행할 주소를 계산하는 계층이 사라지고, 결과 값도 공유 레지스터 파일을 거치지 않고 토큰 라우팅 NoC를 통해 소비 노드로 곧장 건네진다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정적 데이터플로우 vs 동적 데이터플로우**: DFG 간선 하나에 토큰 1개만 허용하는 정적 모델과, 토큰마다 태그를 붙여 다중 인스턴스를 병렬 처리하는 동적 모델.

</details>

```text
1. 선행 PE 연산 완료 후 결과 데이터 기반 토큰 패킷 생성
                      │
                      ▼
2. 온칩 NoC를 통해 목적지 노드의 매칭 유닛으로 토큰 패킷 전송
                      │
                      ▼
3. 매칭 유닛의 발화 규칙(모든 입력 토큰 도착 여부) 판정
   ├── [미도착]: 매칭 메모리에 토큰 보관 후 대기
   └── [도착 완료]: 노드 발화 발생 및 실행 준비 큐 투입
                      │
                      ▼
4. 유휴 PE에 배정되어 즉각 연산 실행 및 후속 토큰 생성
                      │
                      ▼
[결과 전송]: 생성된 토큰을 NoC로 송출하거나 전체 DFG 완료 시 최종 결과 반환
```

분기 결과: 입력 토큰이 미도착이면 매칭 메모리를 점유한 채 대기해 저장 용량을 비용으로 치르고, 도착이 완료되면 **발화 규칙**에 따라 유휴 PE에서 즉시 실행되어 명령 순서를 기다리는 지연 없이 후속 **데이터 토큰**을 생성함

#### 한줄 요약
- 토큰 도착 ➔ 매칭 검사 ➔ 발화 조건 충족 시 PE 실행 ➔ 후속 토큰 생성 및 NoC 전송의 순환 루프로 동작한다.

## Ⅴ. 종류 및 비교

| 아키텍처 패러다임 | 데이터플로우 컴퓨터 (Dynamic) | 전통 폰 노이만 (Control Flow) | 공간형 가속기 (CGRA / TPU) |
|:---|:---|:---|:---|
| 실행 결정 기준 | **발화 규칙** (토큰 가용성) | 프로그램 카운터 (순차 증분) | 클록 파이프라인 스트림 |
| 병렬성 추출 방식 | 하드웨어 DFG 자동 병렬화 | 컴파일러 및 스레드 병렬화 | 공간 매핑 파이프라인 |
| 주요 하드웨어 오버헤드 | 연관 메모리(CAM) 검색 비용 | 명령어 인출 및 분기 예측 | 컴파일 라우팅 스케줄링 |
| 주요 적용 분야 | AI 신경망, 스트리밍 처리 | 범용 운영체제(OS), 제어 로직 | 딥러닝 행렬 곱셈(GEMM) |

#### 한줄 요약
- 복잡한 제어 로직에는 폰 노이만 CPU가 우세하지만, 대규모 데이터 의존성 연산에는 데이터플로우 가속기가 압도적인 효율을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **거친 입도 데이터플로우(Coarse-Grained Dataflow)**: 개별 명령어 단위가 아닌 텐서/타일 단위로 토큰을 묶어 매칭 오버헤드를 극소화하는 현대적 아키텍처.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 명령어 단위 토큰 매칭으로 인한 CAM 메모리 오버헤드 폭증 | **타일 단위 거친 입도(Coarse-Grained)** 데이터플로우 적용 | 매칭 회로 오버헤드 절감 및 연산 밀도 극대화 |
| 루프 병렬성 폭주로 인한 매칭 큐 메모리 오버플로 | 크레딧 기반 **백프레셔(Backpressure)** 흐름 제어 | 버퍼 넘침 원천 차단 및 안정적 큐 깊이 유지 |
| 순차 제어 로직 처리 시의 실행 비효율 | 제어용 **호스트 CPU**와 **데이터플로우 가속기** 이종 융합 | 순차 제어와 대규모 병렬 연산 간 최적 분업 |

#### 한줄 요약
- 실무에서는 Coarse-Grained 타일링으로 매칭 오버헤드를 줄이고, 백프레셔로 큐를 보호하며, CPU와의 하이브리드 결합으로 효율을 극대화한다.

## Ⅶ. 결론

- 프로그램 카운터 종속성을 탈피하여 데이터 의존성(Data Dependency)만으로 연산을 자율 구동하는 비 폰 노이만(Non-Von Neumann) 컴퓨팅의 핵심 모델이며, 현대에는 SambaNova, Cerebras, Graphcore 등 AI 전용 DSA(Domain-Specific Architecture) 및 CGRA(Coarse-Grained Reconfigurable Array) 가속기의 아키텍처적 근간으로 재부상

#### 한줄 요약
- 데이터플로우 컴퓨팅은 폰 노이만 병목을 극복하고 AI와 대규모 병렬 연산의 잠재력을 해금하는 핵심 아키텍처다.
