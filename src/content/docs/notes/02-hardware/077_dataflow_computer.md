## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 흐름 컴퓨터(Dataflow Computer)**: "1번 먼저 해, 2번 해" 하고 순서를 정해주는 프로그램 카운터(PC) 없이, 밥상(데이터)만 차려지면 누구든 숟가락부터 들고 계산해버리는 미친 병렬 아키텍처이다.
- **토큰(Token)**: 데이터 값뿐만 아니라 "이건 A 함수에 쓸 데이터야!" 하고 꼬리표(태그)가 달린 채로 돌아다니는 캡슐 데이터 덩어리이다.
- **발화(Firing)**: 더하기 연산을 하려면 A와 B가 필요한데, 두 토큰이 모두 도착하는 순간 눈치 안 보고 냅다 연산을 터뜨려버리는(실행하는) 현상이다.

</details>

- 정의: 프로그램 카운터(PC) 제어 방식 대신, **토큰**이 모든 필수 노드에 수용되었을 때 노드를 **발화**시키는 **데이터 흐름 컴퓨터**
- 배경: 명령어를 순서대로 한 줄씩만 꺼내서 계산하는 폰 노이만 구조의 답답한 병목(메모리 대기 지연)을 박살 내고, 극한의 병렬성을 뽑아내기 위함

#### 한줄 요약

- 명령 순서를 무시하고, 재료(데이터)가 도착하는 즉시 닥치는 대로 계산을 터뜨려버리는(발화) 초병렬 컴퓨터 아키텍처이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 흐름 그래프(Dataflow Graph)**: 코드를 한 줄 한 줄 쓰지 않고, 데이터가 물 흐르듯 어디서 어디로 흘러갈지 화살표로 그려놓은 작전 지도이다.
- **태그(Tag)**: 루프를 100번 돌 때 데이터들이 섞여서 짬뽕이 안 되도록, "이건 1번째 루프 데이터", "이건 2번째" 라고 딱지를 붙여놓는 식별표이다.
- **토큰 매칭(Token Matching)**: 대기실에서 "철수 데이터 왔냐? 영희 데이터 왔냐?" 하고 짝꿍 데이터가 다 모였는지 멱살 잡고 검사하는 깐깐한 확인 절차이다.

</details>

- 명령어 순서(PC) 따위는 개나 줘버리고, 데이터가 도착하는 즉시 닥치는 대로 계산해버리는 **데이터 흐름 그래프** 기반 비동기 연산임.
- 루프나 재귀 돌릴 때 데이터가 꼬이는 걸 막기 위해 토큰마다 꼬리표를 달아주는 식별용 **태그** 메커니즘을 도입함.
- 코드에 숨어있는 **암묵적 병렬성**을 영혼까지 끌어내어, 조건만 맞으면 기계가 알아서 수천 개의 연산을 무자비하게 동시 처리해버림.

#### 한줄 요약

- 코드 순서(PC) 대신 태그로 짝꿍을 맞춰(토큰 매칭) 데이터가 모이는 즉시 숨은 병렬성을 극강으로 끌어내 연산을 터뜨린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **토큰 매칭 저장소(Matching Unit/Store)**: 꼬리표 달린 토큰들이 모여서 자기 짝꿍 데이터가 올 때까지 죽치고 기다리는 대기실이자 검문소이다.
- **처리 요소(Processing Element, PE)**: 짝꿍이 다 모인 준비된 데이터들을 받아서, 미친 듯이 산술/논리 연산을 갈아버리는 계산 코어(실행 유닛)이다.

</details>

```text
[ 데이터 짝짓기 및 묻지마 병렬 발화 프레임워크 ]
                        [ 데이터 흐름 그래프 (작전 지도) ]
                                      │
[ 처리 요소/실행 유닛 (계산 믹서기) ] ◄── [ 토큰 매칭 저장소 (대기실) ] ◄── 입력 토큰
                                      │
                         [ 출력 계층 (결과물 쏘기) ]
```

| 구성요소 | 책임 |
|:---|:---|
| **데이터 흐름 그래프** | 프로그램 노드 간 데이터가 어떻게 흘러갈지 밑그림(DAG)을 그려놓은 작전 지도 |
| **토큰 매칭 저장소** | 꼬리표(태그) 달린 짝꿍 데이터들이 다 모였는지 멱살 잡고 검사하는 대기실 |
| 준비 노드 스케줄러 | 짝꿍이 다 모인 준비된 놈들만 골라서 연산 코어(**처리 요소**)로 무자비하게 던져버리는 디스패처 |
| **실행 유닛(PE)** | 던져진 데이터를 받아 산술/논리 연산을 수행하고 결과값에 새 꼬리표를 달아 뱉어내는 믹서기 |
| 출력 계층 | 연산이 끝난 결과물들을 모아서 외부 메모리나 화면으로 쏴주는 마지막 관문 |

#### 한줄 요약

- 매칭 저장소에서 짝꿍 데이터가 다 모이면(준비), 스케줄러가 코어(PE)로 던져서 무자비하게 계산을 갈아버린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **준비 노드(Ready Node)**: 연산에 필요한 A 토큰과 B 토큰이 대기실에 모두 도착해서, 당장이라도 계산기에 들어갈 수 있게 몸이 달아오른 상태이다.
- **결과 토큰(Result Token)**: 연산이 끝난 뒤, 그 결과값에 "다음은 C 함수로 가라"는 꼬리표를 붙여서 다시 던져버리는 택배 상자이다.

</details>

```text
[ 무한 병렬 데이터 짝짓기 및 비동기 발화 십자포화 잔혹 흐름 ]
                               │
                               ▼
            ┌────── 실행 가능 노드가 남는 동안 무한 뺑뱅이 ──────┐
            │                                                  │
            │  [ 1. 짝꿍 검사: 꼬리표 까보고 짝꿍 다 왔나 판정 ] │
            │                                                  │
            │                          ▼                       │
            │  [ 2. 묻지마 발화: 준비 노드들을 코어에 냅다 던짐 ]│
            │                                                  │
            │                          ▼                       │
            │  [ 3. 방출: 계산 끝난 결과에 새 꼬리표 달아 던짐 ] │
            └──────────────────────────┬───────────────────────┘
                                       ▼
                       [ 최종 결과 정렬 및 마무리 ]
```

### 동작 원리

1. 짝꿍 검사 및 대기: 날아온 **토큰**들의 꼬리표를 까보고, 연산에 필요한 피연산자 데이터가 다 모였는지 깐깐하게 판정함.
2. 준비 완료 노드 발화: 데이터가 다 모인 **준비 노드**들을 남아도는 **실행 유닛(PE)**에 냅다 던져서 미친 듯이 병렬로 계산을 갈김.
3. 새 토큰 생성 및 방출: 계산이 끝나면 다음 목적지 꼬리표를 붙인 **결과 토큰**을 만들어 다시 대기실로 얄짤없이 던져버림.

#### 한줄 요약

- 대기실에서 꼬리표 보고 짝꿍을 맞춘 뒤, 다 모인 놈들만 코어에 던져서 계산하고 결과물을 다시 대기실로 무한 뺑뺑이 돌린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **제어 흐름 컴퓨터(Control-Flow Computer)**: 우리가 쓰는 일반 PC처럼 프로그램 카운터(PC)가 시키는 대로 한 줄 한 줄 얌전하게 메모리에서 명령을 꺼내오는 모범생 구조이다.

</details>

| 비교 항목 | **데이터 흐름 컴퓨터** (Dataflow) | **제어 흐름 컴퓨터** (Control-Flow) |
|:---|:---|:---|
| 시스템 적용 최적 기준 | 인공지능 딥러닝(TPU)처럼 순서 상관없이 데이터 쏟아지면 미친 듯이 병렬로 갈아버려야 할 시 | 일반 PC처럼 사용자가 클릭하는 순서대로 차근차근 명령을 실행해야 할 시 |
| 아키텍처 핵심 구현 특징 | 순서표(PC) 없이 데이터(토큰)만 다 모이면 알아서 멱살 잡고 연산을 터뜨리는(**발화**) 상남자식 비동기 런타임 | 카운터(PC)가 가리키는 주소대로 한 줄 한 줄 얌전하게 메모리에서 명령을 꺼내오는 모범생 폰 노이만 구조 |
| 극복해야 할 태생적 한계점 | 데이터마다 꼬리표(태그) 달고 짝꿍 찾느라(**토큰 매칭**) 배보다 배꼽이 더 커져 램(메모리)이 터져나감 | 메모리에서 명령 꺼내올 때까지 CPU가 아무것도 안 하고 멍 때리는 환장할 폰 노이만 병목의 노예 |

#### 한줄 요약

- 데이터가 오면 순서 무시하고 패버리는 데이터 흐름 구조와, 줄 서서 순서대로만 처리하는 제어 흐름 구조의 차이이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **백프레셔(Backpressure)**: 대기실에 토큰이 터져나갈 것 같으면, 앞단에 "더 이상 데이터 만들지 마!" 라고 신호를 쏴서 생산을 막아버리는 숨 고르기 기술이다.
- **연산 입도(Coarse-Grained Granularity)**: 1+1 같은 짜잘한 계산마다 꼬리표 달고 짝꿍 찾으면 시간이 다 가니까, 아예 수백 개의 데이터를 한 덩어리(텐서)로 묶어서 한 번에 퉁치는 쿨한 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토큰 하나하나마다 짝꿍 찾느라(**토큰 매칭**) 시간을 다 까먹어서 정작 계산은 뒷전인 멍청한 오버헤드 폭발 | 쪼잔하게 1+1 계산하지 말고 대용량 행렬 덩어리(텐서) 단위로 한 방에 처리하게 **연산 입도**를 무식하게 키움 | 짝꿍 찾는 시간 낭비를 쥐어짜 없애버리고 AI 딥러닝 연산 효율을 한계치까지 극대화 (CGRA/TPU 도입) |
| 루프 연산을 미친 듯이 돌렸더니 대기실에 꼬리표 달린 토큰이 산더미처럼 쌓여서 메모리가 펑 터져버리는 셧다운 | 램 꽉 찰 것 같으면 앞단에 "그만 만들어!" 라고 신호를 때려 막아버리는 얄짤없는 **백프레셔** 피드백 제어 가동 | 메모리 오버플로우로 시스템이 뻗어버리는 대참사를 원천 차단하고 안정적 무한 루프 생존 보장 |
| 계산 끝난 토큰이 다음 노드로 갈 때 멀리 있는 칩까지 배달 가느라 시간이 하루 종일 걸리는 네트워크 지연 | 자주 엮이는 연산 코어들은 아예 물리적으로 딱 붙여버리는(공간적 지역성) 뼈 깎는 칩 물리적 배치 튜닝 강행 | 쓸데없이 칩 안에서 데이터가 여행하는 낭비 시간을 잘라내고 빛의 속도로 다음 연산 돌입 |

#### 한줄 요약

- 짝꿍 찾는 시간이 아까우면 데이터를 크게 묶어서 처리하고(입도 조절), 램 터질 것 같으면 데이터 생산을 멈춰라(백프레셔).

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실행 구조 선택 기준(Execution Architecture Selection Criteria)**: 이 프로그램이 AI처럼 데이터가 무더기로 쏟아지는 구조인지, 아니면 if-else 분기가 많은 순차적 구조인지 견적을 내서 컴퓨터 구조를 고르는 잣대이다.

</details>

- **실행 구조 선택 기준** 원칙에 따라, 차세대 AI 텐서 그래프 병렬 처리는 **Coarse-Grained 데이터 흐름 컴퓨터**로, 분기 중심의 복잡한 순차 제어는 **제어 흐름 컴퓨터**로 채택 기조 확립함

#### 한줄 요약

- AI 행렬 연산처럼 무식하게 쏟아지는 데이터는 데이터 흐름 컴퓨터(TPU)에 박고, 복잡한 로직은 일반 CPU에 맡겨라.
