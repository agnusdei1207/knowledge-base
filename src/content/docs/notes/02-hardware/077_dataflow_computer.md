## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Dataflow Computer(데이터 흐름 컴퓨터)**: 프로그램 카운터(PC)의 지시 대신 연산에 필요한 입력 데이터가 모두 준비되는 순간 연산 노드가 실행되는 비순차 하드웨어 아키텍처.
- **Token(토큰)**: 데이터 값과 목적지 노드 주소, 루프/컨텍스트 식별자(Tag)가 결합된 최소 정보 패킷.
- **Firing Rule(발화 규칙)**: 연산 노드가 필요로 하는 모든 입력 토큰이 매칭 유닛에 도착했을 때 즉각 연산을 개시하는 트리거 조건.

</details>

- 정의/개념: 프로그램 카운터(PC)의 순차적 명령어 인출(Fetch) 방식 대신, 연산에 필요한 모든 피연산자(Operand) 데이터(토큰)가 준비되는 즉시 노드를 발화(Firing)시켜 연산을 수행하는 비순차 데이터 구동(Data-Driven) 컴퓨터 아키텍처
- 배경/필요성: 폰 노이만 구조의 제어 흐름(Control-Flow) 병목과 메모리 지연 장벽을 극복하고, **프로그램 내재적 병렬성(Implicit Parallelism)을 극대화하여 대규모 AI/과학 연산 처리**

#### 한줄 요약

- PC 순차 제어 없이 **데이터 토큰 가용성에 의해 즉시 발화(Firing)되는 데이터 구동형 초병렬 아키텍처**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Dataflow Graph(DAG)**: 프로그램의 연산 노드와 데이터 의존성을 방향성 비순환 그래프로 모델링한 실행 표현.
- **Tagged-Token Architecture**: 동일한 연산 노드가 반복 실행(루프, 재귀)될 때 토큰마다 고유 태그를 부여하여 데이터 충돌 없이 병렬 실행하는 구조.

</details>

- 명령어 주소 순서가 아닌 데이터 의존성 그래프(DAG)에 따라 비동기적으로 연산을 개시하는 **데이터 구동 실행(Data-Driven Execution)**
- 다중 루프 반복과 함수 호출 시 데이터를 식별하기 위해 토큰에 컨텍스트 ID를 부여하는 **태그 기반 토큰 매칭(Tagged Token)**
- 프로그래머의 명시적 스레드 분기 없이도 그래프 상의 독립 노드를 동시에 처리하는 **암묵적 병렬성(Implicit Parallelism) 극대화**

#### 한줄 요약

- **비순차 데이터 구동 발화(Firing Rule)·태그 기반 토큰 매칭(Tagged Token)·암묵적 병렬성 극대화**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Matching Unit(매칭 유닛)**: 유입된 토큰의 태그와 목적지 노드를 비교하여 짝꿍 피연산자가 모두 모였는지 검사하는 하드웨어 버퍼.
- **Processing Element(PE, 처리 요소)**: 준비 완료된 토큰을 받아 ALU 연산을 수행하고 새로운 목적지 태그를 붙여 방출하는 연산 코어.

</details>

```text
[ 데이터 흐름 컴퓨터 매칭 및 발화 아키텍처 ]
┌─────────────────────────────────────────────────────────────┐
│ 1. 데이터 흐름 그래프 메모리 (DAG Node & Routing Table)      │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 입력 토큰 스트림 <Data, Tag, Node> ]
┌──────────────────────────────┴──────────────────────────────┐
│ 2. 토큰 매칭 저장소 (Matching Unit / Token Store)            │
│  ├─ 짝꿍 피연산자 도착 대기 (Associative Search)             │
│  └─ 완전 매칭 시 발화 패킷 형성 (Firing Packet)             │
└──────────────────────────────┬──────────────────────────────┘
                               │ [ 3. 준비 노드 디스패치 ]
┌──────────────────────────────┴──────────────────────────────┐
│ 4. 처리 요소 어레이 (PE Array : ALU / Floating-Point Core)  │
│  └─ 5. 결과 토큰 생성 ──> NoC 라우팅 ──> 후속 노드 매칭 전파 │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 데이터 흐름 그래프(DAG), 토큰 매칭 저장소(Matching Unit), 준비 노드 디스패처, 처리 요소(PE 어레이) 및 출력 라우팅 간의 데이터 흐름 컴퓨터 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 흐름 그래프 | 프로그램 노드 간 데이터가 어떻게 흘러갈지 밑그림(DAG)을 그려놓은 작전 지도 |
| 토큰 매칭 저장소 | 꼬리표(태그) 달린 짝꿍 데이터들이 다 모였는지 멱살 잡고 검사하는 대기실 |
| 준비 노드 스케줄러 | 짝꿍이 다 모인 준비된 놈들만 골라서 연산 코어(**처리 요소**)로 무자비하게 던져버리는 디스패처 |
| 실행 유닛(PE) | 던져진 데이터를 받아 산술/논리 연산을 수행하고 결과값에 새 꼬리표를 달아 뱉어내는 믹서기 |
| 출력 계층 | 연산이 끝난 결과물들을 모아서 외부 메모리나 화면으로 쏴주는 마지막 관문 |

#### 한줄 요약

- **데이터 흐름 그래프(DAG)·토큰 매칭 저장소(Matching Unit)·준비 노드 스케줄러·처리 요소(PE 어레이)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Ready Node**: 연산에 필요한 모든 입력 토큰($A, B$)이 매칭 저장소에 수집되어 즉시 PE로 전달 가능한 상태의 노드.

</details>

```text
[ 데이터 토큰 매칭 및 PE 비동기 발화 시퀀스 ]
                         │
                         ▼
   [ 1. 입력 토큰 도착 및 태그(<Context, Iteration, Node>) 추출 ]
                         │
                         ▼
   [ 2. 매칭 유닛 검색 : 동일 태그의 짝꿍 피연산자 매칭 여부 검사 ]
        /                                               \
   [ 미완료 (첫 번째 토큰 도착) ]                     [ 완료 (모든 토큰 집합 완료) ]
        │                                               │
   [ 매칭 저장소에 토큰 보관 대기 ]                [ 3. 발화(Firing) : 준비 노드 형성 ]
                                                        │
                                                        ▼
                                           [ 4. 가용 PE에 연산 디스패치 ]
                                                        │
                                                        ▼
                                           [ 5. 새 목적지 태그 부착 결과 토큰 방출 ]
```

**동작 원리**

1. **토큰 유입**: 연산 결과 또는 외부 입력으로부터 데이터 값과 태그가 포함된 토큰 인입
2. **연관 매칭**: 매칭 유닛이 동일한 목적지 노드 및 컨텍스트 태그를 가진 피연산자가 있는지 검색
3. **발화(Firing)**: 2항 연산자의 두 피연산자가 모두 모이면 Ready Node 상태로 전환하고 발화 트리거
4. **PE 연산**: 디스패처가 준비된 노드를 유휴 PE 코어로 라우팅하여 산술 연산 수행
5. **결과 토큰 방출**: 연산 결과에 DAG 명세에 따른 다음 목적지 노드 주소와 태그를 붙여 NoC 패브릭으로 방출

#### 한줄 요약

- 토큰 인입 및 태그 검사 $\to$ **피연산자 완전 매칭(Ready Node) $\to$ 가용 PE 발화(Firing) 및 연산 $\to$ 목적지 태그 부착 결과 토큰 생성 $\to$ 후속 노드 전파**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Dataflow vs Control-Flow**:
  - Dataflow: 데이터 가용성 기반 비동기 발화, 프로그램 카운터(PC) 없음, 암묵적 병렬성 극대화
  - Control-Flow: PC 기반 순차 명령어 인출(Von Neumann), 명시적 멀티스레딩, 분기 로직 특화

</details>

| 비교 항목 | 데이터 흐름 컴퓨터 (Dataflow) | 제어 흐름 컴퓨터 (Control-Flow : Von Neumann) |
|:---|:---|:---|
| 실행 구동 원리 | 데이터 가용성 기반 비동기 발화 (Data-Driven) | 프로그램 카운터(PC) 기반 순차 인출 (Control-Driven) |
| 병렬성 추출 방식 | 컴파일 타임 DAG 기반 암묵적 병렬성 자동 추출 | 멀티스레딩, OoO 실행, 벡터 명령어 등 명시적 제어 |
| 한계 및 오버헤드 | 토큰 매칭 메모리 및 태그 오버헤드 (AI/CGRA 적합) | 메모리-CPU 간 폰 노이만 병목 (범용 순차 제어 적합) |

#### 한줄 요약

- 데이터 가용성 기반은 **데이터 흐름(Dataflow)**, PC 순차 제어는 **제어 흐름(Control-Flow)**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Coarse-Grained Granularity**: 단일 명령어 단위(Fine-Grained)의 토큰 매칭 오버헤드를 줄이기 위해 수백~수천 개의 연산을 묶은 텐서/블록 단위로 매칭을 수행하는 아키텍처(CGRA).
- **Backpressure Mechanism**: 매칭 저장소나 PE 큐가 포화 상태에 도달할 때 상위 프로듀서 노드의 토큰 생성을 일시 정지시키는 흐름 제어 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토큰 하나하나마다 짝꿍 찾느라(**토큰 매칭**) 시간을 다 까먹어서 정작 계산은 뒷전인 멍청한 오버헤드 폭발 | 쪼잔하게 1+1 계산하지 말고 대용량 행렬 덩어리(텐서) 단위로 한 방에 처리하게 **연산 입도**를 무식하게 키움 | 짝꿍 찾는 시간 낭비를 쥐어짜 없애버리고 AI 딥러닝 연산 효율을 한계치까지 극대화 (CGRA/TPU 도입) |
| 루프 연산을 미친 듯이 돌렸더니 대기실에 꼬리표 달린 토큰이 산더미처럼 쌓여서 메모리가 펑 터져버리는 셧다운 | 램 꽉 찰 것 같으면 앞단에 "그만 만들어!" 라고 신호를 때려 막아버리는 얄짤없는 **백프레셔** 피드백 제어 가동 | 메모리 오버플로우로 시스템이 뻗어버리는 대참사를 원천 차단하고 안정적 무한 루프 생존 보장 |
| 계산 끝난 토큰이 다음 노드로 갈 때 멀리 있는 칩까지 배달 가느라 시간이 하루 종일 걸리는 네트워크 지연 | 자주 엮이는 연산 코어들은 아예 물리적으로 딱 붙여버리는(공간적 지역성) 뼈 깎는 칩 물리적 배치 튜닝 강행 | 쓸데없이 칩 안에서 데이터가 여행하는 낭비 시간을 잘라내고 빛의 속도로 다음 연산 돌입 |

#### 한줄 요약

- **Coarse-Grained 블록/텐서 입도화(CGRA)·크레딧 기반 백프레셔(Backpressure)·NoC 공간 배치 최적화**
