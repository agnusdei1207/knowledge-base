## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터플로우 컴퓨터(Dataflow Computer)**: 프로그램 카운터(PC)에 의한 순차 명령 인출 대신, 연산에 필요한 입력 데이터(토큰)가 모두 도착하면 즉시 실행하는 비-폰노이만 컴퓨팅 아키텍처.
- **발화 규칙(Firing Rule)**: 특정 연산 노드의 모든 입력 포트에 유효한 데이터 토큰이 준비되었을 때 실행 큐로 투입되는 조건.

</details>

- 정의/개념: 프로그램 카운터(PC) 없이 데이터 가용성에 의해 연산이 트리거되는 **데이터플로우 컴퓨터**
- 배경/필요성: 기존 폰 노이만 제어 흐름 구조로는 **순차적 PC 병목 및 대규모 데이터 병렬성 추출 한계**

#### 한줄 요약
- 명령 순서가 아닌 데이터 의존성에 따라 연산을 실행하여 알고리즘 내재 병렬성을 극대화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **토큰(Token)**: 데이터플로우 그래프 상에서 연산 노드로 전달되는 데이터 값과 태그의 캡슐화 단위.
- **암묵적 병렬성(Implicit Parallelism)**: 프로그래머가 명시적 스레드를 생성하지 않아도 독립적인 데이터 경로가 자동으로 동시 실행되는 특성.

</details>

- 입력 피연산자 토큰이 모두 충족되면 실행되는 **발화 규칙(Firing Rule)** 기반 구동
- 컴파일러가 생성한 데이터 의존성 그래프(DFG)를 통한 **암묵적 병렬성** 극대화
- 동적 데이터플로우 환경에서 루프 및 재귀 호출 식별을 위한 **태그(Tag)** 매칭 지원

#### 한줄 요약
- 토큰 매칭 기반 발화 규칙을 통해 순차 제어 오버헤드 없이 고유의 병렬성을 하드웨어적으로 추출한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **데이터플로우 그래프(DFG)**: 연산 노드(Actor)와 데이터 전달 간선(Arc)으로 프로그램의 데이터 의존성을 표현한 방향성 그래프.
- **매칭 유닛(Matching Unit)**: 연산 노드의 모든 입력 피연산자 토큰이 도착했는지 연관 메모리로 검사하는 하드웨어.

</details>

```text
[데이터플로우 프로세서 아키텍처]
|-- 토큰 입력 및 라우팅 NoC
|-- 매칭 메모리 유닛 (Matching Unit - 연관 메모리 태그 매칭)
|-- 명령 인출 및 DFG 디코더 (준비된 노드 템플릿 로드)
|-- 실행 가능 작업 큐 (Ready Queue)
|-- 처리 요소 어레이 (PE Array - 다중 ALU 및 MAC)
`-- 토큰 생성 및 분배기 (결과 데이터를 후속 노드로 패킷 전송)
```

선의 의미: 계층 및 토큰 순환 파이프라인

| 구성요소 | 책임 |
|:---|:---|
| **매칭 유닛** | 도착한 토큰의 목적지 노드 ID와 태그를 비교하여 피연산자 짝 맞춤 수행 |
| 노드 메모리 | 연산 종류(Opcode)와 후속 목적지 주소가 정의된 **DFG** 노드 템플릿 보관 |
| 실행 작업 큐 | 모든 입력이 충족된 발화 가능 노드를 PE 어레이로 스케줄링 |
| 처리 요소(PE) | 산술·논리 연산을 실행하고 결과 데이터를 패킷 형태로 생성 |
| 토큰 라우팅 NoC | 생성된 결과 토큰을 목적지 노드의 매칭 유닛으로 고속 전송 |

#### 한줄 요약
- 매칭 유닛, 노드 메모리, 실행 큐, PE 어레이, 토큰 라우터가 순환 파이프라인을 구성한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정적 데이터플로우(Static Dataflow)**: DFG 간선 하나에 최대 1개의 토큰만 허용하는 단순 구조 모델.
- **동적 데이터플로우(Dynamic Dataflow)**: 토큰마다 태그(Tag)를 붙여 루프와 재귀 함수 인스턴스를 동시 처리하는 모델.

</details>

```text
선행 노드에서 연산 완료 후 결과 토큰 생성
        │
   온칩 라우터를 통해 목적지 노드의 매칭 유닛으로 토큰 전송
        │
   해당 노드의 모든 입력 토큰(포트 및 태그)이 도착했는가? (발화 규칙)
   ┌────┴─────┐
아니오          예
   │             │
매칭 메모리에   노드 발화(Fire) → 준비 큐(Ready Queue)로 투입
대기 보관         │
   │        유휴 PE(Processing Element)에 배정되어 연산 실행
   │             │
   │        새로운 결과 토큰 생성 후 후속 노드로 라우팅
   └────┬────────┘
        │
   그래프 종료 노드 도달 시 최종 출력 반환
```

#### 한줄 요약
- 토큰 도착 → 매칭 검사 → 발화 조건 충족 시 PE 실행 → 후속 토큰 생성 및 라우팅 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **폰 노이만 제어 흐름(Control Flow)**: 프로그램 카운터(PC)가 가리키는 메모리 주소에서 순차적으로 명령을 가져와 실행하는 전통적 구조.

</details>

| 아키텍처 모델 | 정적 데이터플로우 | 동적 데이터플로우 | 폰 노이만 제어 흐름 | 공간형 가속기 (CGRA/TPU) |
|:---|:---|:---|:---|:---|
| 실행 결정 기준 | 모든 입력 포트의 토큰 도착 | 동일 태그의 입력 토큰 도착 | 프로그램 카운터(PC) 순차 증분 | 고정된 데이터 스트림 파이프라인 |
| 재귀 및 루프 처리 | 불가 (단일 토큰 제약) | 완벽 지원 (태그 기반 식별) | 스택 및 분기 명령어로 처리 | 루프 언롤링 및 공간 매핑 |
| 주요 하드웨어 오버헤드 | 토큰 대기 래치 | 연관 매칭 메모리 검색 비용 | 순차 인출 및 분기 예측 실패 | 정적 컴파일 라우팅 복잡도 |
| 대표 응용 | 단순 신호 처리 파이프라인 | 범용 병렬 알고리즘 | 범용 운영체제 및 순차 로직 | 심층 신경망 텐서 연산 가속 |

#### 한줄 요약
- 범용 프로그램은 폰 노이만 구조가 우세하지만, AI 텐서 연산에는 데이터플로우 공간 가속기가 압도적인 효율을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **토큰 큐 오버플로우**: 무한 병렬성 폭주로 인해 토큰 메모리가 고갈되는 현상을 방지하는 스케줄링 대책.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 세밀한 명령어 단위 토큰 매칭으로 오버헤드 과다 | 블록/타일 단위 거친 입도(Coarse-Grained) 데이터플로우 적용 | 매칭 회로 오버헤드 절감 및 연산 밀도 향상 |
| 루프 병렬성 폭주로 매칭 메모리 오버플로우 | 크레딧 기반 토큰 흐름 제어(Backpressure) 적용 | 버퍼 고갈 방지 및 안정적 토큰 큐 유지 |
| 복잡한 조건 분기 및 순차 로직 실행 시 비효율 | 제어 흐름 CPU 코어와 데이터플로우 DPU의 이종 결합 | 순차 제어와 병렬 연산 간 최적 분업 실현 |
| 노드 간 토큰 통신 지연으로 인한 PE 유휴 | 2D 토러스 NoC 및 공간적 지역성 기반 컴파일 매핑 | 라우팅 홉 수 최소화 및 연산기 가동률 극대화 |

#### 한줄 요약
- Coarse-Grained 타일링, 백프레셔 흐름 제어, CPU 하이브리드 결합, NoC 공간 매핑으로 실효 성능을 확보한다.

## Ⅶ. 결론

- AI 텐서 연산 및 스트리밍 신호 처리는 **데이터플로우 공간 가속기(DSA)**를 구축하고, 순차 제어 CPU와 결합한 **이기종 하이브리드 아키텍처** 확립

#### 한줄 요약
- 데이터플로우 컴퓨팅은 폰 노이만 병목을 극복하고 AI 및 고성능 컴퓨팅의 대규모 병렬성을 해금하는 핵심 아키텍처다.
