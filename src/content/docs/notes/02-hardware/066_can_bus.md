## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN(Controller Area Network)**: 차량 및 산업용 기기 내에서 마이크로컨트롤러(ECU) 간에 호스트 컴퓨터 없이 직접 통신을 가능하게 하는 표준 직렬 버스 네트워크.
- **메시지 식별자(CAN ID)**: 노드의 물리 주소가 아닌 데이터의 종류와 송신 우선순위를 나타내는 11비트(표준) 또는 29비트(확장) 헤더.

</details>

- 정의/개념: 노드 주소가 아닌 **메시지 식별자(CAN ID)**로 우선순위를 정해 충돌 없이 중재하는 차동 2선식 멀티마스터 버스 **CAN(Controller Area Network)**
- 배경/필요성: 제어기를 점대점으로 잇는 방식은 부품이 늘수록 배선 중량과 비용이 제곱에 가깝게 증가하고 노이즈에도 취약

#### 한줄 요약
- 주소가 아니라 데이터 종류로 통신한다는 설계 덕분에 노드를 늘려도 기존 노드를 고칠 필요가 없으며, 차량 전장이 이 구조 위에서 확장돼 왔다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비파괴 비트 단위 중재(Non-Destructive Bitwise Arbitration)**: 여러 노드가 동시 송신할 때 우성(Dominant, 0) 비트를 보낸 노드가 버스를 계속 차지하고 열성(Recessive, 1) 노드는 즉시 수신으로 전환되어 충돌 손실이 없는 방식.
- **버스 오프(Bus-Off)**: 특정 노드의 전송 에러 카운터(TEC)가 255를 초과하면 버스 전체의 마비를 막기 위해 해당 노드를 버스에서 강제 격리하는 안전 기능.

</details>

- 물리 주소 없이 메시지 식별자로 방송하고 수신 측이 필터링
- 동시 송신 시에도 **비파괴 비트 단위 중재(Non-Destructive Bitwise Arbitration)**로 재전송 불필요
- 에러 카운터 기반 3단계 격리를 거쳐 최종적으로 **버스 오프(Bus-Off)**로 노드 분리

#### 한줄 요약
- 중재에서 진 노드가 데이터를 잃지 않고 다음 기회를 기다린다는 점이 이 버스의 결정적 성질이며, 그래서 최악 지연을 계산할 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN 컨트롤러**: 메시지 프레임 생성, 비트 스터핑, CRC 계산, 에러 카운팅을 수행하는 디지털 로직.
- **CAN 트랜시버**: 로직 레벨(0/1) 신호를 CAN_H, CAN_L 차동 전압 신호로 변환하는 아날로그 PHY 칩.

</details>

```text
[CAN 노드와 버스]
├─ 노드
│  ├─ ECU 마이크로컨트롤러
│  ├─ CAN 컨트롤러 (프레임화·중재·CRC·에러 카운팅)
│  ├─ 수신 메시지 필터 (관심 ID만 통과)
│  └─ CAN 트랜시버 (로직 신호 ↔ 차동 전압 변환)
└─ 버스
   ├─ 차동 꼬임선 (CAN_H·CAN_L)
   └─ 양 끝단 120Ω 종단 저항
```

선의 의미: 가지(`├─`)는 소유 관계이며, 모든 노드가 같은 두 가닥에 병렬로 매달려 있어 한 노드의 신호가 전체에 즉시 나타남

| 구성요소 | 책임 |
|:---|:---|
| **CAN 컨트롤러** | 프레임화·중재·비트 스터핑·CRC 검증 수행 |
| **CAN 트랜시버** | 로직 전압을 차동 신호로 변환해 송수신 |
| 차동 꼬임선 버스 | 두 선에 같이 실린 노이즈를 상쇄해 신호 보호 |
| 종단 저항 | 양 끝단에서 반사파를 흡수해 신호 왜곡 방지 |
| 수신 메시지 필터 | 관심 식별자만 통과시켜 인터럽트 부하 절감 |

#### 한줄 요약
- 노이즈 내성이 프로토콜이 아니라 두 선의 전압 차이라는 물리 구조에서 나오므로, 소프트웨어로는 결코 얻을 수 없는 종류의 강건성이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우성(Dominant 0) vs 열성(Recessive 1)**: 두 노드가 동시에 0과 1을 보내면 버스에는 전압차가 발생하여 물리적으로 '0'이 승리하는 원리.

</details>

```text
버스 유휴 감지 → 대기 노드들이 동시에 송신 시작
        │
   식별자 비트를 보내며 버스 실제 값과 비교
        │
   내가 보낸 비트와 버스 값이 같은가?
   ┌────┴─────┐
  예           아니오 (열성 보냈는데 우성 관측)
   │             │
다음 비트 계속   즉시 송신 중단 후 수신 전환
   │             (데이터 손실 없음)
   │
중재 승리 → 데이터 필드까지 완주
        │
   정상 수신 노드가 응답 슬롯을 우성으로 구동했는가?
   ┌────┴─────┐
  예           아니오
   │             │
전송 성공      에러 카운터 증가 후 재전송
```

분기 결과: 진 노드가 다음 유휴 시점에 그대로 재시도하므로 중재는 손실 없는 우선순위 결정이 되지만, 그 대가로 낮은 우선순위 메시지의 지연 상한은 버스 부하에 좌우됨

#### 한줄 요약
- **우성(Dominant 0) vs 열성(Recessive 1)**이라는 전기적 비대칭 하나가 충돌 해소를 대신하므로, 이 프로토콜의 중재 로직은 사실상 회로가 수행한다.

## Ⅴ. 종류 및 비교

| 차량용 네트워크 프로토콜 | Classical CAN 2.0 | CAN FD | LIN | Automotive Ethernet |
|:---|:---|:---|:---|:---|
| 적용 기준 | 엔진/변속기/바디 기본 제어 네트워크 | 대용량 센서/ADAS 제어 데이터 전송 | 도어/시트/창문 등 초저가 서브네트워크 | 자율주행 라이다/카메라/도메인 제어기 |
| 핵심 특징 | 명목 1Mbps 이하와 8바이트 페이로드 | 데이터 구간 가변 속도와 64바이트 페이로드 | 1선식 UART 기반 스케줄 통신 | 스위치 기반 고속 IP 통신 |
| 한계 | 대역폭 부족으로 대규모 데이터 전송 불가 | 트랜시버 교체 필요 및 배선 토폴로지 민감 | 극저속 및 마스터 단일 제어로 응답성 한계 | 높은 케이블/트랜시버 단가 및 전력 소비 |

#### 한줄 요약
- 네 프로토콜은 대역폭과 결정성을 맞바꾼 눈금이며, 빨라질수록 중재로 얻던 예측 가능성을 스위치와 스케줄링으로 다시 만들어야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비트 스터핑(Bit Stuffing)**: 동일한 비트가 5개 연속되면 동기 유지를 위해 반대 극성의 비트 1개를 강제로 삽입하는 규칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 결함 노드가 에러 프레임을 반복해 버스 전체 마비 | 에러 카운터 임계 초과 시 버스 오프 전환과 복구 정책 | 결함 노드 자동 격리와 네트워크 복원 |
| 종단 저항 누락이나 배선 반사로 에러 급증 | 버스 양 끝단에 규격 종단 저항 정확히 장착 | 반사파 흡수와 고속 통신 안정화 |
| 방송 구조라 메시지 위조·재전송이 쉬움 | 인증 태그와 신선도 값 부착, 게이트웨이 필터 적용 | 위조·재전송 탐지와 도메인 간 전파 제한 |
| 버스 부하 상승으로 저순위 메시지 지연 확대 | 응답 시간 분석 후 주기·식별자 조정과 버스 분할 | 최악 중재 지연을 마감시간 이내로 제한 |

#### 한줄 요약
- 인증이 프로토콜에 없어 상위 계층으로 얹혀야 하는데, 1980년대에 신뢰할 수 있는 폐쇄망을 전제로 설계된 구조가 지금의 위협 모델과 어긋나는 지점이다.

## Ⅶ. 결론

- 짧은 제어 메시지와 우선순위 중재가 필요하면 CAN 계열을, 고대역폭 백본은 차량용 이더넷을 선택하고, 안전성은 버스 오프 하나에 기대지 말고 응답 시간 분석·물리 종단·인증·게이트웨이 정책으로 계층화

#### 한줄 요약
- 이 버스가 40년 가까이 살아남은 이유는 성능이 아니라 최악 지연을 계산할 수 있다는 점이며, 대체 기술은 그 계산 가능성부터 다시 증명해야 한다.
