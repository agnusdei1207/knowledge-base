## 미리 알고가기

- **제어기 영역 네트워크(Controller Area Network, CAN)**: 제어 메시지를 공유 차동 선로로 방송하는 차량용 통신 버스
- **전자 제어 장치(Electronic Control Unit, ECU)**: 센서 입력과 제어 로직에 따라 차량 기능을 제어하는 내장 컴퓨터
- **메시지 식별자(Message Identifier, ID)**: CAN 프레임의 메시지 의미와 버스 중재 우선순위를 나타내는 필드
- **우성·열성 비트(Dominant·Recessive Bit)**: 중재 중 우성 비트가 선로를 점유하는 신호
- **비파괴 중재(Non-Destructive Arbitration)**: 승자 프레임을 손상하지 않는 중재
- **비트 스터핑(Bit Stuffing)**: 같은 비트 5개 뒤 반대 비트 삽입
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: CAN 프레임 전송 중 발생한 비트 오류를 검출하는 코드
- **수신 확인(Acknowledgement, ACK)**: 하나 이상의 수신 노드가 프레임을 정상 수신했음을 표시하는 필드
- **오류 격리(Error Confinement)**: 오류 누적 노드의 송신 권한 제한
- **가변 데이터 전송률 CAN(CAN Flexible Data Rate, CAN FD)**: 데이터 필드를 최대 64바이트로 확장하고 데이터 구간의 전송률을 높인 CAN 규격
- **버스 오프(Bus-off)**: 송신 오류 누적 노드의 버스 분리 상태
- **차동 신호선(CAN High·CAN Low, CAN_H·CAN_L)**: 두 신호선의 전압 차로 비트를 전달하여 공통 모드 잡음의 영향을 줄이는 CAN 물리 계층 신호
- **다중 마스터(Multi-master)**: 여러 노드가 중앙 제어기 없이 버스 사용을 요청하고 중재 결과에 따라 송신하는 구조
- **발행·구독(Publish·Subscribe)**: 송신자는 ID로 메시지를 방송하고 수신자는 필요한 ID만 필터링하는 통신 방식
- **CAN 컨트롤러·트랜시버(CAN Controller·Transceiver)**: 컨트롤러는 프레임·중재·오류를 처리하고 트랜시버는 논리 비트와 차동 신호를 변환함
- **종단 저항(Termination Resistor)**: 버스 양 끝에서 신호 반사를 흡수해 파형 왜곡을 줄이는 저항
- **프레임·페이로드(Frame·Payload)**: 프레임은 제어 필드를 포함한 전송 단위이고 페이로드는 그 안의 실제 데이터
- **게이트웨이(Gateway)**: 서로 다른 차량 통신망 사이에서 메시지를 전달·필터링하는 장치

## Ⅰ. 개요

- 정의/개념: 메시지 ID로 **비파괴 중재**하는 다중 마스터 버스
- 기존 한계: 점대점 차량 배선은 **배선량·제어 통합 비용** 증가

### 쉽게 이해하기 (학습용)

- 여러 장치가 한 무전 채널에서 번호가 작은 긴급 메시지부터 끊김 없이 말하는 방식이다.

## Ⅱ. 특징

- **메시지 ID 발행·구독**으로 송수신 노드 결합 완화
- **우성 비트 비파괴 중재**로 높은 우선순위 프레임 보존
- **버스 부하·ID 우선순위**가 최악 응답시간 결정

### 쉽게 이해하기 (학습용)

- 작은 번호가 먼저 말하고 채널이 붐빌수록 큰 번호는 더 기다리며 오류 장치는 퇴장하지만 발언자 신원은 따로 확인한다.

## Ⅲ. 아키텍처 및 구성요소

### 도표안 A. CAN 노드와 공유 버스 정적 구조

```mermaid
flowchart LR
    subgraph ECU[전자 제어 장치]
        A[응용 소프트웨어]
        C[CAN 컨트롤러]
        T[CAN 트랜시버]
        A <-->|메시지| C
        C <-->|논리 비트| T
    end
    B[CAN_H·CAN_L·종단]
    N([다른 CAN 노드])
    T <-->|차동 신호| B
    B <-->|방송| N
```

| 설계 요소 | 입력·상태 | 역할 |
|:---|:---|:---|
| 응용 소프트웨어 | 메시지 값·주기·ID | 발행·수신 조건 설정 |
| CAN 컨트롤러 | 메시지·버스·오류 카운터 | 프레임·중재·필터·오류 처리 |
| CAN 트랜시버 | 논리 비트·선로 상태 | 차동 전기 신호 변환 |
| CAN_H·CAN_L·종단 | 차동 신호·배선 임피던스 | 방송 전달·반사 억제 |

> 요약: 트랜시버가 프레임을 차동 신호로 변환한다

### 쉽게 이해하기 (학습용)

- 응용 프로그램이 쪽지를 만들면 컨트롤러가 봉투를 씌우고 송수신기가 두 가닥 선에 싣는다.

### 도표안 B. CAN 비파괴 중재와 프레임 전달 시퀀스

```mermaid
sequenceDiagram
    participant A as 고우선순위 송신 ECU
    participant CA as 송신 CAN 컨트롤러 A
    participant B as 저우선순위 송신 ECU
    participant CB as 송신 CAN 컨트롤러 B
    participant W as CAN 버스
    participant CR as 수신 CAN 컨트롤러
    participant R as 수신 ECU

    A->>CA: ① 작은 ID의 프레임 송신 요청
    B->>CB: ② 큰 ID의 프레임 송신 요청
    CA->>W: ③ SOF·ID 비트 송신
    CB->>W: ④ SOF·ID 비트 송신
    W-->>CA: ⑤ 실제 버스 비트 피드백
    W-->>CB: ⑥ 실제 버스 비트 피드백
    CB-->>B: ⑦ 중재 패배·재전송 대기
    CA->>W: ⑧ 승자 프레임 나머지 전송
    W->>CR: ⑨ 프레임 전달·CRC 검사
    CR->>W: ⑩ 정상 수신 ACK 우성 비트
    W-->>CA: ⑪ ACK 슬롯 관측
    CA-->>A: ⑫ 송신 완료 통지
    CR->>R: ⑬ ID 필터를 통과한 페이로드 전달
    W-->>CB: ⑭ 버스 유휴 통지
    CB->>W: ⑮ 보류 프레임 재중재
```

#### 동작 원리

1. **고우선순위 요청**: ECU A가 상대적으로 작은 ID를 가진 프레임의 송신을 컨트롤러에 요청한다.
2. **저우선순위 요청**: ECU B도 버스가 유휴인 시점에 큰 ID 프레임의 송신을 요청한다.
3. **첫 번째 중재 참여**: 컨트롤러 A가 프레임 시작과 ID 비트를 차례로 버스에 출력한다.
4. **두 번째 중재 참여**: 컨트롤러 B도 같은 방식으로 프레임 시작과 ID 비트를 출력한다.
5. **A의 버스 감시**: 컨트롤러 A가 자신이 보낸 값과 실제 버스의 우성·열성 값을 비트마다 비교한다.
6. **B의 버스 감시**: 컨트롤러 B도 자신이 보낸 값과 실제 버스 값을 비트마다 비교한다.
7. **중재 패배**: 열성 비트를 보낸 컨트롤러 B가 우성 비트를 관측하면 송신을 중단하되 오류로 처리하지 않고 재전송을 기다린다.
8. **승자 프레임 보존**: 중재에서 이긴 컨트롤러 A가 프레임을 중단 없이 계속 전송한다.
9. **프레임 검증**: 수신 컨트롤러가 프레임을 받고 형식·비트 스터핑·CRC를 검사한다.
10. **정상 수신 확인**: 오류 없이 받은 수신 컨트롤러가 ACK 슬롯에 우성 비트를 출력한다.
11. **ACK 관측**: 송신 컨트롤러 A가 ACK 슬롯의 우성 비트를 보고 하나 이상의 노드가 정상 수신했음을 확인한다.
12. **송신 완료**: 컨트롤러 A가 송신 ECU에 성공을 알린다.
13. **메시지 전달**: 수신 컨트롤러가 ID 필터를 통과한 페이로드를 수신 ECU에 전달한다.
14. **유휴 감지**: 패배한 컨트롤러 B가 프레임 종료 뒤 버스 유휴 상태를 확인한다.
15. **재중재**: 컨트롤러 B가 보류 프레임을 다시 송신하며 다른 대기 노드와 중재한다.

### 쉽게 이해하기 (학습용)

- 동시에 말해도 작은 ID의 우성 비트가 이기며, 패자는 승자의 메시지를 망가뜨리지 않고 다음 차례를 기다린다.

## Ⅳ. 종류 및 비교

| 차량 통신 방식 | CAN | CAN FD | 자동차 이더넷 |
|:---|:---|:---|:---|
| 적용 기준 | 차체·섀시의 **짧은 제어** | 진단·센서·**업데이트 데이터** | 카메라·백본의 **대용량 데이터** |
| 핵심 특징 | ID 중재의 **제어 프레임** | 빠른 데이터·**확장 페이로드** | 스위치 기반 **대용량 전송** |
| 한계 | 저순위 지연·**대역폭 한계** | 노드 호환·**비트 타이밍** | 시간 동기·**보안 복잡성** |

> 요약: 짧은 제어는 CAN, 대용량은 CAN FD를 택한다

### 쉽게 이해하기 (학습용)

- 짧은 쪽지는 CAN, 큰 묶음은 CAN FD, 영상 화물은 이더넷으로 보낸다.

## Ⅴ. 실무 고려사항 및 대응 방안

| 운영 위험 | 대응 | 기대 효과 |
|:---|:---|:---|
| 높은 버스 부하에서 저순위 ID 기아 | 최악 응답시간 분석·주기 조정·부하 상한 적용 | 제어 마감시간 보장 |
| 오류 노드의 반복 버스 오프·무조건 복귀 | 오류 원인 진단 후 제한된 복귀·재시도 정책 적용 | 장애 폭주 방지 |
| 종단·배선·접지 문제로 반사·공통 모드 오류 | 양 끝 종단·파형·오류 카운터와 배선 길이 검증 | 물리 계층 안정화 |
| ID가 송신자 인증을 제공하지 않아 위조 가능 | 게이트웨이 필터·메시지 인증·진단 접근 통제 | 제어 메시지 신뢰성 강화 |

### 쉽게 이해하기 (학습용)

- 번호 경쟁에서 진 장치는 다시 기다리고 오류가 쌓인 장치는 무전 채널에서 빠진다.

### 적용 사례

- 차체 제어망은 메시지별 주기·전송시간·마감시간을 분석해 더 긴급한 메시지에 우선순위가 높은 작은 CAN ID를 배정한다.

### 쉽게 이해하기 (학습용)

- 차체 제어는 더 급한 메시지에 작은 ID를 주고 최악 대기시간을 계산한다.

## Ⅵ. 결론

- 차량 제어 메시지를 제한시간 안에 신뢰성 있게 전달하기 위해 **식별자 우선순위·버스 부하·최악 응답시간·오류 격리**를 검토하고, 요구를 만족하는 제어망에 CAN을 적용한다

### 쉽게 이해하기 (학습용)

- 메시지가 제때 도착하고 오류 노드를 격리할 수 있을 때 CAN을 선택한다.
