## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN(Controller Area Network, ISO 11898)**: 차량 및 산업용 분산 제어 환경에서 마이크로컨트롤러(ECU) 간에 호스트 컴퓨터 없이 2선식 차동 버스를 통해 고신뢰성 통신을 지원하는 표준 직렬 통신 네트워크.
- **메시지 식별자(CAN ID)**: 노드의 물리적 하드웨어 주소가 아닌 전송 데이터의 의미(엔진 RPM, 차속 등)와 우선순위를 나타내는 11비트(표준) 또는 29비트(확장) 헤더.

</details>

- 정의/개념: **메시지 식별자(CAN ID)** 기반의 비파괴 비트 중재와 하드웨어 결함 격리(Bus-Off)를 지원하는 2선식 차동 직렬 통신 **CAN 버스 아키텍처**
- 배경/필요성: 차량 내 전자제어장치(ECU) 급증에 따른 배선 하네스의 중량·원가 폭증 및 **가혹한 전자기 노이즈(EMI) 환경에서의 통신 신뢰성 한계**

#### 한줄 요약
- CAN은 노드 주소 대신 메시지 ID 우선순위로 버스를 중재하고 차동 꼬임선으로 노이즈를 상쇄하는 차량용 표준 네트워크 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비파괴 비트 단위 중재(Non-Destructive Bitwise Arbitration)**: 복수 노드가 동시 송신할 때 우성(Dominant 0) 비트를 전송한 노드가 버스를 계속 점유하고 열성(Recessive 1) 노드는 즉시 수신으로 전환되어 데이터 충돌 손실이 없는 메커니즘.
- **버스 오프(Bus-Off)**: 전송 에러 카운터(TEC)가 255를 초과한 결함 노드를 버스 선로에서 물리적으로 강제 격리하여 네트워크 전체 마비를 차단하는 안전 기능.

</details>

- 방송 및 하드웨어 필터링: 모든 노드가 버스 프레임을 수신하되, 수신 필터(Acceptance Filter)를 통해 관심 ID만 인터럽트 수신
- 우선순위 중재: 비파괴 비트 중재로 승자 프레임을 유지하고 패자는 재시도
- 자동 결함 격리: 전송 에러 카운터 기반 3단계 전이를 통해 결함 노드를 **버스 오프(Bus-Off)**로 자동 분리

#### 한줄 요약
- 비파괴 중재로 충돌 지연을 없애고, 에러 카운터 기반 버스 오프로 결함 노드를 자동 격리하여 신뢰성을 확보한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN 컨트롤러(CAN Controller)**: 프레임 패킷화, 비트 스터핑, CRC 검증, 비트 중재 및 에러 카운팅을 하드웨어로 수행하는 디지털 로직.
- **CAN 트랜시버(CAN Transceiver)**: 디지털 로직 레벨(TxD/RxD 0/1) 신호를 CAN_H, CAN_L 차동 전압 레벨로 상호 변환하는 아날로그 물리 계층(PHY) 칩.
- **차동 꼬임선(Twisted Pair)**: 두 선의 전압 차로 동상 잡음 영향을 줄이는 물리 계층 배선.

</details>

```text
+-------------------------------------------------------------------------------+
|                       CAN 노드 및 2선식 차동 버스 아키텍처                   |
|                                                                               |
|  +---------------------------+             +-------------------------------+  |
|  |     ECU 노드 1 (엔진)     |             |      ECU 노드 N (브레이크)    |  |
|  |  [ 호스트 MCU / AUTOSAR ] |             |  [ 호스트 MCU / AUTOSAR ]     |  |
|  |             │             |             |               │               |  |
|  |  +---------------------+  |             |  +-------------------------+  |  |
|  |  | CAN 컨트롤러 (MAC)  |  |             |  | CAN 컨트롤러 (MAC)      |  |  |
|  |  | - 비트 타이밍/중재  |  |             |  | - 수신 필터/CRC/에러카운터|  |  |
|  |  +---------------------+  |             |  +-------------------------+  |  |
|  |             │ TxD / RxD   |             |               │ TxD / RxD     |  |
|  |  +---------------------+  |             |  +-------------------------+  |  |
|  |  | CAN 트랜시버 (PHY)  |  |             |  | CAN 트랜시버 (PHY)      |  |  |
|  +--+---------------------+--+             +--+-------------------------+--+  |
|                │       │                               │       │              |
|        CAN_H   │       │ CAN_L                 CAN_H   │       │ CAN_L        |
|  +-------------┼-------┼-------------------------------┼-------┼-----------+  |
|  | [120Ω] <====╪=======╪===============================╪=======╪====> [120Ω]| |
|  | 종단저항    ▼       ▼       2선식 차동 꼬임선 버스  ▼       ▼      종단저항| |
|  |         CAN_H (우성 3.5V / 열성 2.5V)                                    | |
|  |         CAN_L (우성 1.5V / 열성 2.5V)  --> 차동 전압 Vdiff = 2.0V (0)     | |
|  +-------------------------------------------------------------------------+  |
+-------------------------------------------------------------------------------+
```

- 신호 및 연결 관계: 각 ECU의 트랜시버는 TxD/RxD 로직 신호를 2선식 차동 전압(CAN_H/CAN_L)으로 변환하여 버스에 물려 있으며, 양단에 설치된 120Ω 종단 저항(`[120Ω]`)이 고속 전송 신호의 반사파를 흡수함을 명시함

| 구성요소 | 책임 |
|:---|:---|
| 호스트 MCU | 센싱 처리와 송신 메시지 큐 관리 |
| **CAN 컨트롤러** | 중재·CRC와 TEC·REC 오류 관리 |
| **CAN 트랜시버** | 로직과 **CAN**_H·CAN_L 전압 변환 |
| **차동 꼬임선** | 동상 잡음 억제와 멀티드롭 연결 |
| 120Ω 종단 저항 | 버스 양 끝의 신호 반사 억제 |

#### 한줄 요약
- CAN 컨트롤러가 호스트 MCU 소프트웨어를 대신해 중재·CRC·오류 계수를 하드웨어로 처리하고, 트랜시버가 로직 레벨과 차동 전압 사이에 끼어들어 단선 기준 신호가 감당하지 못하던 잡음을 두 선의 전압 차로 상쇄하므로 노드 증설이 배선 신설이 아니라 버스 분기로 끝난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우성(Dominant 0) vs 열성(Recessive 1)**: 두 노드가 동시에 0과 1을 송출하면 버스 라인은 2.0V 차동 전압이 발생하여 물리적으로 우성인 '0' 상태가 승리하는 와이어드-AND(Wired-AND) 논리.

</details>

```text
[버스 유휴(Idle) 상태 감지]
           │
           ▼
1. 복수 노드의 SOF(Start of Frame) 동시 송출 개시
           │
           ▼
2. CAN ID 비트열 순차 송출 및 수신 라인 동시 피드백 감시
           │
           ▼
3. 송출 비트와 버스 감시 비트의 일치 여부 비교 판정
    ┌──────────────────────┴──────────────────────┐
 [ 일치 (우성 0 전송 중 0 감지) ]             [ 불일치 (열성 1 전송 중 0 감지) ]
    │                                             │
    ▼                                             ▼
4. 중재 승리: 다음 비트 및 데이터 프레임 송출 계속    4. 중재 패배: 즉각 송신 중단 및 수신 모드 전환
    │                                             │
    ▼                                             │
5. 전 수신 노드의 CRC 검증 및 ACK 슬롯 응답 확인  │
    ┌──────────────────────┴──────────────────────┤
 [ ACK 수신 성공 ]                             [ ACK 실패 / 전송 오류 ]
    │                                             │
    ▼                                             ▼
전송 완료 및 다음 유휴 주기 대기              TEC 카운터 증가 및 다음 유휴 시 재전송
```

- 분기 결과: 식별자 숫자가 낮을수록(**우성** 0이 많을수록) 중재에서 승리하여 지연 없이 전송되며, 패배한 노드는 손실 없이 즉시 수신으로 전환됨

**동작 원리**

1. 버스가 유휴 상태임을 감지한 복수의 노드가 동시에 SOF(Start of Frame) 우성 비트를 송출하며 전송을 개시한다.
2. 각 노드는 CAN ID의 최상위 비트(MSB)부터 한 비트씩 전송하면서 동시에 트랜시버 수신 핀(RxD)으로 버스 실제 레벨을 읽어 들인다.
3. 노드가 열성('1')을 보냈으나 버스에서 우성('0')이 감지되면 자신이 중재에서 패배했음을 인지하고 송신 구동을 즉각 중단한다.
4. 중재에서 승리한 최우선순위 노드는 프레임 깨짐 없이 데이터 필드와 CRC 시퀀스를 버스로 연속 송출한다.
5. 메시지를 정상 수신한 모든 노드가 ACK 슬롯에 우성 비트를 실어 응답하며, 송신 노드는 ACK 확인 후 전송을 성공 종료하고 패배 노드는 차기 유휴 시 재전송한다.

#### 한줄 요약
- 우성 비트가 열성을 덮는 물리 특성만으로 중재를 끝내 충돌 재전송 비용을 없애는 대신, 식별자가 큰 노드의 전송 시점은 구조적으로 뒤로 밀리는 것을 감수한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAN FD(Flexible Data-rate)**: 데이터 필드 전송 속도를 최대 5~8Mbps로 가변 가속하고 페이로드를 최대 64바이트로 확장한 차세대 CAN 표준.
- **LIN(Local Interconnect Network)**: 단일 마스터-다중 슬레이브 구조의 1선식 UART 기반 초저가 차량용 서브네트워크.

</details>

| 차량용 통신 프로토콜 | Classical CAN 2.0A/B | CAN FD (Flexible Data-rate) | LIN (Local Interconnect) | 차량용 이더넷 (Automotive) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 레거시 차량 파워트레인 및 범용 ECU 간 기본 제어 시 | ADAS 센서 및 섀시 제어 대용량(최대 64B) 고속 전송 시 | 도어/미러/시트 등 저속 단순 편의 장치 초저비용 배선 연결 시 | 자율주행 라이다/카메라 대용량 영상 및 중앙 백본망 구축 시 |
| 전송 속도 (대역폭) | 최대 1 Mbps | 최대 5~8 Mbps (가변 가속) | 최대 20 kbps (저속) | 100 Mbps ~ 10 Gbps |
| 최대 페이로드 크기 | 8 바이트 | 64 바이트 | 8 바이트 | 1500 바이트 (표준 프레임) |
| 버스 토폴로지 | 2선식 멀티드롭 차동 버스 | 2선식 멀티드롭 차동 버스 | 1선식 단일 버스 | 스위치 기반 스타형 |
| 주요 적용 분야 | 파워트레인 기본 제어 | ADAS 센서, 섀시 제어 | 도어 록, 시트 편의 장치 | 자율주행 백본 네트워크 |

#### 한줄 요약
- 기본 제어에는 CAN 2.0, 대용량 실시간 제어에는 CAN FD, 단순 편의 장치에는 **LIN**, 대용량 센서/백본에는 차량용 이더넷이 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SecOC(Secure Onboard Communication)**: AUTOSAR 표준 보안 프로토콜로, CAN 메시지에 메시지 인증 코드(MAC)와 신선도 값(Freshness Value)을 부착하여 스푸핑 및 재전송 공격을 차단하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 결함 노드의 에러 프레임 폭주 | **에러 카운터 기반 Bus-Off 자동 격리** | 불량 노드가 버스에 미치는 영향 제한 |
| 종단 저항 미부착에 따른 신호 반사파 | **양 끝단 120Ω 종단 저항 실장** | 반사 억제로 신호 무결성 개선 |
| 브로드캐스트 특성에 따른 스푸핑 위협 | **AUTOSAR SecOC MAC 인증** 적용 | 패킷 위변조 및 재생 공격 차단 |

#### 한줄 요약
- 실무에서는 Bus-Off로 결함을 격리하고, 120Ω 종단 저항으로 반사파를 막으며, **SecOC**로 보안 위변조를 차단한다.

## Ⅶ. 결론

- 차량용 파워트레인 및 섀시 분산 제어의 글로벌 표준 네트워크(ISO 11898)로 확고히 안착되었으며, 최근에는 대용량 센서 데이터를 수용하는 CAN FD(최대 5~8Mbps, 64바이트) 및 CAN XL(최대 10~20Mbps)로 고도화됨과 동시에 SDV 시대를 맞아 초고속 차량용 이더넷 백본 및 Zonal 아키텍처와 계층적으로 융합하고 있으므로 전장 엔지니어는 120Ω 종단 정합과 AUTOSAR SecOC 암호 인증을 필수로 적용해야 한다.

#### 한줄 요약
- CAN 버스는 비파괴 중재와 Bus-Off 결함 격리를 통해 40년간 검증된 자동차 전장 네트워크의 핵심 표준이다.
