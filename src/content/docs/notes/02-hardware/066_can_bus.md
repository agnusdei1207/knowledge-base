## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN(Controller Area Network)**: 차량 및 산업용 기기 내에서 마이크로컨트롤러(ECU) 간에 호스트 컴퓨터 없이 직접 통신을 가능하게 하는 표준 직렬 버스 네트워크.
- **메시지 식별자(CAN ID)**: 노드의 물리 주소가 아닌 데이터의 종류와 송신 우선순위를 나타내는 11비트(표준) 또는 29비트(확장) 헤더.

</details>

- 정의/개념: 차량·산업용 제어기 사이에서 **메시지 ID 기반 비파괴 비트 중재**를 수행하는 차동 2선식 멀티마스터 버스
- 배경/필요성: 차량 내 전장 부품 증가에 따른 점대점 배선 하네스 중량·비용 증가 극복 및 노이즈 내성 강화 필요

#### 한줄 요약
- 자동차 안의 수많은 제어 장치들을 2가닥의 꼬임선(Twisted Pair)만으로 연결해 서로 데이터를 주고받게 하는 네트워크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비파괴 비트 단위 중재(Non-Destructive Bitwise Arbitration)**: 여러 노드가 동시 송신할 때 우성(Dominant, 0) 비트를 보낸 노드가 버스를 계속 차지하고 열성(Recessive, 1) 노드는 즉시 수신으로 전환되어 충돌 손실이 없는 방식.
- **버스 오프(Bus-Off)**: 특정 노드의 전송 에러 카운터(TEC)가 255를 초과하면 버스 전체의 마비를 막기 위해 해당 노드를 버스에서 강제 격리하는 안전 기능.

</details>

- 물리 주소 대신 **메시지 ID 기반 브로드캐스트** 및 수신 필터링
- 버스 동시 송신 시 데이터 손실 없는 **비파괴 비트 단위 중재(Wired-AND)**
- 에러 카운터(TEC/REC) 기반 3단계 결함 격리(Error Active → Error Passive → **Bus-Off**)

#### 한줄 요약
- 작은 ID의 우성 비트가 중재에서 이기고 오류가 누적된 노드는 Bus-Off로 격리된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN 컨트롤러**: 메시지 프레임 생성, 비트 스터핑, CRC 계산, 에러 카운팅을 수행하는 디지털 로직.
- **CAN 트랜시버**: 로직 레벨(0/1) 신호를 CAN_H, CAN_L 차동 전압 신호로 변환하는 아날로그 PHY 칩.

</details>

```text
┌─────────────────────────────────────────────────────────────┐
│ CAN 노드 아키텍처 및 차동 2선식 버스 구조                  │
│                                                             │
│  [ ECU 마이크로컨트롤러 ] ── (Tx/Rx 로직 레벨)              │
│  └───────────┬───────────────────────────────────────────┐  │
│              ▼                                           │  │
│  ┌───────────────────────┐                               │  │
│  │ CAN 컨트롤러 (MAC 계층)│                               │  │
│  └───────────┬───────────┘                               │  │
│              ▼ (TxD / RxD)                               │  │
│  ┌───────────────────────┐                               │  │
│  │ CAN 트랜시버 (PHY 계층)│                               │  │
│  └───────────┬───────────┘                               │  │
│              │ (차동 전압 구동)                          │  │
│  ════════════╪═══════════════════════════════════════════╪═ │
│  CAN_H 선 ───┴─────────────────────────── [ 120Ω 종단 ] ─┴─ │
│  CAN_L 선 ─────────────────────────────── [ 120Ω 종단 ] ─── │
│  (Twisted Pair 꼬임선 차동 버스 구조)                       │
└─────────────────────────────────────────────────────────────┘
```

선의 의미: 트랜시버가 CAN_H(3.5V)와 CAN_L(1.5V)의 전압차(2.0V, Dominant 0)를 생성하여 120Ω 종단 버스로 전송

| 구성요소 | 책임 |
|:---|:---|
| CAN 컨트롤러 | 프레임 패킷화, CSMA/NBA 중재, 비트 스터핑(5연속 1비트 삽입), CRC 무결성 검증 |
| CAN 트랜시버 | 단일 종단 로직 전압을 노이즈에 강한 CAN_H/CAN_L 차동 신호로 변환 송수신 |
| 차동 꼬임선 버스 | 외부 전자기 노이즈(EMI)를 상쇄(Common-Mode Noise Rejection)하여 신호 보호 |
| 120Ω 종단 저항 | 버스 양 끝단에서 고주파 신호의 반사파(Reflection)를 흡수하여 신호 왜곡 방지 |
| 수신 메시지 필터 | 수신할 CAN ID만 마스킹 통과시켜 MCU의 불필요한 인터럽트 부하 절감 |

#### 한줄 요약
- MCU, CAN 컨트롤러, CAN 트랜시버, 차동 꼬임선, 120옴 종단 저항이 하나의 강건한 통신망을 이룬다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **우성(Dominant 0) vs 열성(Recessive 1)**: 두 노드가 동시에 0과 1을 보내면 버스에는 전압차가 발생하여 물리적으로 '0'이 승리하는 원리.

</details>

```text
버스 유휴(Idle) 상태 감지
      │
      ▼
1. 버스 유휴 확인
      │
      ▼
2. 비트 중재
      │
      ▼
3. 충돌 없는 승패 결정
      │
      ▼
4. 승자 프레임 완주
      │
      ▼
5. 무결성 ACK 확인
```

**동작 원리**

1. **버스 유휴 확인**: 버스가 연속 11비트 이상 열성 상태일 때 송신 대기 노드들이 프레임 시작(SOF)
2. **비트 중재**: ID의 최상위 비트(MSB)부터 전송하면서 자신이 쏜 비트와 버스의 실제 비트를 비교
3. **충돌 없는 승패 결정**: 자신이 1을 보냈는데 버스가 0이면 우선순위가 밀린 것이므로 즉각 송신 중단
4. **승자 프레임 완주**: 중재에서 이긴 최우선 노드는 아무런 지연이나 패킷 손상 없이 데이터 필드까지 완주
5. **무결성 ACK 확인**: 정상 수신한 하나 이상의 노드가 ACK 슬롯을 우성으로 구동

#### 한줄 요약
- 동시 송신 → 비트 비교 중재 → 열성 노드 즉시 포기 → 우성 노드 완주 → 수신 노드 ACK 회수 순으로 동작한다.

## Ⅴ. 종류 및 비교

| 차량용 네트워크 프로토콜 | Classical CAN 2.0 | CAN FD | LIN | Automotive Ethernet |
|:---|:---|:---|:---|:---|
| 적용 기준 | 엔진/변속기/바디 기본 제어 네트워크 | 대용량 센서/ADAS 제어 데이터 전송 | 도어/시트/창문 등 초저가 서브네트워크 | 자율주행 라이다/카메라/도메인 제어기 |
| 핵심 특징 | 명목 1Mbps 이하와 8바이트 페이로드 | 데이터 구간 가변 속도와 64바이트 페이로드 | 1선식 UART 기반 스케줄 통신 | 스위치 기반 고속 IP 통신 |
| 한계 | 대역폭 부족으로 대규모 데이터 전송 불가 | 트랜시버 교체 필요 및 배선 토폴로지 민감 | 극저속 및 마스터 단일 제어로 응답성 한계 | 높은 케이블/트랜시버 단가 및 전력 소비 |

#### 한줄 요약
- 범용 차량 제어는 Classical CAN, 대용량 전송은 CAN FD, 단순 편의 장치는 LIN, 초고속 대용량은 이더넷을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **비트 스터핑(Bit Stuffing)**: 동일한 비트가 5개 연속되면 동기 유지를 위해 반대 극성의 비트 1개를 강제로 삽입하는 규칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 결함 노드가 끊임없이 에러 프레임을 쏘아 **버스 전체 마비** | 컨트롤러의 **Bus-Off 상태 전환(TEC > 255)** 및 소프트웨어 리셋 제어 | 악성 결함 노드 자동 고립 및 네트워크 복원 |
| 종단 저항 누락 또는 배선 반사로 인한 **신호 왜곡 및 에러 폭증** | 버스 양 끝단에 **정확한 120Ω 스플릿 종단 저항** 장착 | 신호 반사파 흡수 및 고속 통신 안정화 |
| 브로드캐스트 특성에 따른 **메시지 위조·재전송** | **SecOC 인증 태그·신선도 값**과 게이트웨이 필터 적용 | 위조·재전송 탐지와 도메인 간 전파 제한 |
| 높은 버스 부하에 따른 **저순위 메시지 지연** | 응답시간 분석 후 주기·ID 조정, CAN FD·버스 분할 적용 | 최악 중재 지연을 마감시간 이내로 제한 |

#### 한줄 요약
- Bus-Off로 고장 장치를 격리하고, 120옴 종단으로 왜곡을 막으며, SecOC로 해킹을 차단한다.

## Ⅶ. 결론

- 짧은 제어 메시지와 우선순위 중재는 **CAN·CAN FD**, 고대역폭 백본은 Automotive Ethernet 선택
- 안전성은 Bus-Off만 믿지 말고 응답시간 분석·물리 종단·SecOC·게이트웨이 정책으로 계층화

#### 한줄 요약
- 비파괴 비트 중재와 차동 2선식 하드웨어 구조, SecOC 보안 체계를 결합하여 차량 전장 네트워크의 안전성과 신뢰성을 보장해야 한다.
