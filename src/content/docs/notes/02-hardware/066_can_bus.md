## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **캔 통신(Controller Area Network, CAN)**: 자동차 안의 브레이크, 엔진, 에어백들이 서로 "내가 먼저 말할래!" 하고 싸우지 않게, 단 두 가닥의 구리선(CAN-H, CAN-L)으로 교통정리를 해주는 뼛속 깊은 차량 표준 통신망이다.
- **다중 마스터(Multi-Master)**: 학교 선생님(중앙 호스트) 없이, 버스가 조용해지면 학생(ECU) 누구나 눈치껏 손을 들고 먼저 말을 꺼낼 수 있는 평등하면서도 살벌한 구조이다.
- **비파괴 중재(Non-Destructive Arbitration)**: 두 놈이 동시에 말할 때, 충돌해서 둘 다 망하는(파괴) 게 아니라, 목소리 큰 놈(우선순위가 높은 놈)이 이기고 진 놈은 알아서 주둥이를 닫는 쿨한 방식이다.

</details>

- 정의: 차동 신호선(CAN-H/CAN-L) 상에서 메시지 식별자(ID) 비트 단위 논리 비교를 통해 **비파괴 중재**를 수행하는 **다중 마스터** 버스 프로토콜인 **캔 통신**
- 배경: 자동차에 전자 장비(ECU)가 미친 듯이 늘어나면서 구리선 뭉치(하네스) 무게 때문에 연비가 박살 나는 걸 막고, 선 두 가닥만으로 통신 신뢰성을 멱살 잡고 끌어올리기 위함

#### 한줄 요약

- 수십 개의 자동차 부품이 두 가닥 선에 물려 있으면서도, 급한 놈(에어백)이 무조건 먼저 말할 수 있게 교통정리를 해주는 기가 막힌 통신 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **메시지 아이디(Message ID)**: "나는 엔진 칩이다"가 아니라 "이건 브레이크 정보(ID: 0x123)다!"라고 메시지 자체에 번호표를 달아, 번호가 작을수록 무조건 1빠로 통과시키는 깡패 식별자이다.
- **발행 구독(Publish-Subscribe)**: "야, 핸들아! 브레이크 정보 받아!"가 아니라, 그냥 허공(버스)에 외치면(발행) 필요한 놈들만 알아서 주워 먹는(구독) 쿨한 방송 방식이다.
- **우성 열성 비트(Dominant/Recessive Bit)**: 0은 깡패(우성)고 1은 찐따(열성)라서, 선 위에서 0과 1이 부딪히면 무조건 0이 1을 덮어씌우고 이겨버리는 하드웨어 물리 법칙이다.
- **최악 응답 시간(Worst-Case Response Time, WCRT)**: 덜 급한 메시지들이 버스를 점령해서 차가 꽉 막힌 최악의 지옥 같은 상황에서도, 내 메시지가 뚫고 나가는 데 걸리는 시간이다.

</details>

- "누구한테 보낸다"는 노드 주소 대신 "이건 브레이크 정보다"라는 메시지 의미 기반의 **발행 구독** 방송 통신 방식을 뼛속까지 채택함.
- 버스에서 동시에 떠들 때 0(**우성 비트**)이 1(열성 비트)을 짓밟고 덮어씌워, 번호가 작은 ID가 무자비하게 주도권을 차지하는 냉혹한 **비파괴 중재**를 강제함.
- 하드웨어 에러 카운터(TEC/REC) 기반으로 불량 노드를 색출해 시스템에서 강제로 쫓아내는 버스 오프(Bus-Off) 물리선 노이즈 차단을 수행함.

#### 한줄 요약

- 0(우성)이 1(열성)을 이기는 법칙을 써서, 번호가 작은(0이 많은) 급한 메시지가 부딪힘 없이 버스를 꿀꺽 삼킨다(비파괴 중재).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **캔 컨트롤러(CAN Controller)**: 번호표를 보고 순서를 정하며, 에러가 났는지(CRC) 깐깐하게 검사하고 비트 스터핑 꼼수까지 부리는 칩셋의 뇌하수체이다.
- **캔 트랜시버(CAN Transceiver)**: 컨트롤러의 얌전한 디지털 신호를, 자동차 엔진의 험악한 노이즈를 뚫고 나갈 수 있는 강력한 차동 전압(CAN-H/L)으로 뻥튀기하는 근육이다.
- **차동 버스 종단(Differential Bus & Termination)**: 두 선을 꽈배기처럼 꼬아서 외부 노이즈를 서로 씹어먹고 상쇄하며, 양 끝에 120옴(Ω) 저항을 달아 신호가 벽에 부딪혀 튕겨 나오는 걸 억제하는 고속도로이다.

</details>

```text
[ 캔 통신 노드 데이터 변환 및 노이즈 차단 송수신 아키텍처 ]
                        [ 응용 소프트웨어 (브레이크 제어 앱) ]
                                      │
[ 캔 컨트롤러 (뇌하수체: 중재 및 에러 검사) ] ─── [ 캔 트랜시버 (근육: 차동 전압 변환) ]
                                                         │
                        [ 차동 버스 꼬임선 (CAN-H/L) & 120Ω 종단 저항 ]
```

| 구성요소 | 책임 |
|:---|:---|
| 응용 소프트웨어 | 브레이크를 밟았는지 판단하고, "가장 급함(작은 ID)" 번호표를 할당해 메시지 박스에 밀어 넣는 앱 |
| **캔 컨트롤러** | 번호표를 보고 순서를 정하며, 에러가 났는지(CRC) 깐깐하게 검사하는 뇌하수체 논리 칩셋 |
| **캔 트랜시버** | 컨트롤러의 약해 빠진 디지털 신호를 자동차의 험악한 노이즈를 뚫을 수 있는 강력한 차동 전압(CAN-H/L)으로 뻥튀기하는 근육 |
| **차동 버스 종단** | 꼬임선으로 노이즈를 서로 씹어먹고 상쇄하며, 양 끝에 120옴(Ω) 저항을 달아 신호 반사파 튕김을 억제하는 전송 도로 |

#### 한줄 요약

- 소프트웨어가 만든 메시지를 컨트롤러가 규칙에 맞게 포장하고, 트랜시버가 전압을 높여 꼬임선(차동 버스)으로 쏴버린다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **경쟁 아이디 비트열(Contending ID Bits)**: 서로 먼저 말하겠다고 여러 칩들이 동시에 버스에 침을 뱉어보는 식별자 비트들의 눈치싸움이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: 데이터가 가다가 노이즈에 쳐맞고 깨졌는지 확인하기 위해, 꼬리표에 붙여놓은 15비트짜리 수학적 검증 암호이다.
- **수신 확인(Acknowledgement, ACK)**: 메시지를 멀쩡하게 잘 받았다고, 버스에 0(우성 비트)을 쾅 찍어주는 "잘 받았음!" 확인 도장이다.

</details>

```text
[ 캔 버스 멱살 잡기 비파괴 중재 및 에러 검출 반복 생존 흐름 ]
                               │
                               ▼
    [ 1. 눈치싸움 중재: 버스가 비면 여러 칩들이 경쟁 아이디 비트열을 1비트씩 냅다 쏨 ]
                               │
                               ▼
   [ 2. 패자 강제 항복: 자기는 1을 쐈는데 버스에서 0이 읽히면, 즉시 입 닫고 수신 모드로 엎드림 ]
                               │
                               ▼
 [ 3. 승자 독식 전송: 끝까지 살아남은(가장 0이 많은) 놈이 버스를 삼키고 무파괴 연속 전송 강행 ]
                               │
                               ▼
     [ 4. 십자포화 검증: 수신 놈들이 데이터가 노이즈에 깨졌는지 순환 중복 검사(CRC)로 뼛속 검증 ]
                               │
            +---------------------------------------+
            |      [ 5. 검증 결과 에러가 났는가? ]      |
            |      /                        \       |
            |   [ 아니요 ]                 [ 예 ]     |
            |     │                          │      |
            | 수신 확인(ACK) 도장 쾅      에러 깃발 흔들고 전송 파투   |
            +---------------------------------------+
```

### 동작 원리

1. 아이디 비트 눈치싸움 중재: 버스가 조용해지면, 여러 칩(ECU)들이 동시에 자기 **경쟁 아이디 비트열**을 1비트씩 버스에 냅다 쏨.
2. 우성 1비트 패배자 강제 항복: 자기는 1(열성)을 쐈는데 버스에서 0(우성)이 읽히면 "내가 졌네" 하고 즉시 주둥이를 닫고 수신 모드로 엎드림.
3. 최우선순위 승자 프레임 독식: 끝까지 살아남은 가장 번호가 작은(우선순위가 높은) 메시지가 버스를 통째로 집어삼키고 무파괴 연속 전송을 강행함.
4. 가혹한 십자포화 프레임 검증: 받는 놈들이 데이터가 덜 왔는지, 깨졌는지 **순환 중복 검사**(CRC)로 뼛속까지 검증함.
5. 수신 확인 및 에러 깽판: 멀쩡하면 **수신 확인**(ACK)을 쏘고, 깨졌으면 다 같이 에러 깃발을 흔들어 밥상을 엎어버리고 재시도함.

#### 한줄 요약

- 비트 단위로 0(우성)이 1(열성)을 이겨서 승자를 정하고, 데이터가 깨졌으면 수신 확인(ACK) 대신 에러를 뿜어 재전송하게 만든다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **캔 에프디(CAN Flexible Data-Rate, CAN FD)**: 기존 CAN이 8바이트밖에 못 보내서 답답하니까, 중간 데이터 구간만 엑셀을 밟아 64바이트를 쑤셔 넣는 업그레이드 버전이다.
- **오토모티브 이더넷(Automotive Ethernet)**: 자율주행 카메라 4K 영상처럼 CAN으로는 씨알도 안 먹히는 미친 용량의 데이터를, 랜선 기술을 개조해 차에 쑤셔 박은 기가비트 백본이다.

</details>

| 차량 통신 방식 | **클래식 캔** (Classical CAN) | **캔 에프디** (CAN FD) | **오토모티브 이더넷** (Automotive Ethernet) |
|:---|:---|:---|:---|
| 시스템 적용 최적 기준 | 브레이크, 창문 열기처럼 짧고 굵은 한방이 필요한 소형 제어 메시지 전송 시 | 자율주행 레이더처럼 8바이트로는 턱도 없는 대용량 데이터 전송 및 펌웨어 갱신 시 | 카메라 4K 비전이나 라이다처럼 기가바이트(GB) 단위의 데이터가 미친 듯이 쏟아질 시 |
| 아키텍처 핵심 구현 특징 | 8바이트 페이로드밖에 못 보내는 **캔 통신**의 구식 고정 비트율(최대 1Mbps) 아키텍처 | 아이디 중재 끝나면 엑셀을 밟아 속도를 높이고 페이로드를 64바이트로 늘린 **캔 에프디** | 구리선 2가닥으로 기가비트 속도를 찢어버리는 초고속 스위치 라우팅 기반 **오토모티브 이더넷** |
| 극복해야 할 태생적 한계점 | 데이터 대역폭이 쥐꼬리만 해서 요즘 나오는 자율주행차 백본에는 씨알도 안 먹히는 한계 | 기존 구식 CAN 칩셋들이랑 한 버스에 섞어 쓰면 에러 뿜고 뻗어버리는 물리적 혼용 제약 발생 | 스위치 칩이 비싸서 차값이 오르고, 해킹당하면 차가 통째로 털리는 치명적 IP 보안 위협 |

#### 한줄 요약

- 짧은 제어는 클래식 CAN, 조금 긴 데이터는 엑셀 밟는 CAN FD, 자율주행 카메라는 랜선(오토모티브 이더넷)을 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **버스 부하(Bus Load)**: 차가 얼마나 막히는지 나타내는 퍼센트(%)로, 이게 70%를 넘어가면 덜 중요한 메시지(ID 번호가 큰 놈)는 평생 못 나갈 수도 있다.
- **버스 오프(Bus-Off)**: 엔진 스파크 때문에 에러가 계속 나서 카운터(TEC)가 255를 찍으면, 미친 놈으로 간주하고 버스에서 선을 뽑아 강제로 쫓아내는 자폭 기능이다.
- **시큐어 온보드 커뮤니케이션(Secure Onboard Communication, SecOC)**: 해커가 브레이크 메시지를 위조 못 하게, 오토사(AUTOSAR)에서 메시지 꼬리에 암호화 도장(MAC)을 쾅 찍어버리는 철통 보안 룰이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 똥차들이 버스를 점령해서(**버스 부하** 폭발) 덜 중요한 메시지가 평생 못 나가고 썩어버리는 무한 지연 셧다운 사태 | 메시지 ID를 뼛속까지 뜯어고쳐 우선순위를 칼같이 재배정하고, 전체 부하 상한선을 깐깐하게 강제 통제 | 아무리 차가 막혀도 에어백 터뜨리는 메시지만큼은 무조건 제시간(**최악 응답 시간**)에 뚫고 나가는 생존 보장 |
| 비가 오거나 엔진 스파크가 튀어서 특정 칩이 미쳐 날뛰며 에러를 뿜어내 버스 전체를 마비시키는 연쇄 참사 발발 | 에러를 계속 뿜어내는 놈을 카운팅(TEC)하다가 한계치(255)를 넘으면 물리 선에서 강제로 쫓아냄(**버스 오프**) | 고장 나서 미쳐 날뛰는 칩 하나 때문에 버스 전체가 셧다운되는 최악의 연쇄 폭발 사태 원천 차단 |
| 해커가 외부에서 "브레이크 밟아!"라는 가짜 CAN 메시지를 몰래 쑤셔 넣어 운전자를 죽이는 스푸핑 끔찍한 공격 | AUTOSAR **시큐어 온보드 커뮤니케이션**(SecOC) 규격을 떡칠하여 메시지 끝에 암호화 인증 도장(MAC)을 강제 부여 | 메시지 위변조 및 어제 보낸 메시지를 오늘 다시 쏘는 기만적인 재전송(Replay) 해킹 공격 100% 얄짤없이 방어 |

#### 한줄 요약

- 급한 메시지는 아이디 번호를 작게 주고, 미쳐서 에러 뿜는 칩은 버스에서 쫓아내며(버스 오프), 해커가 짝퉁 메시지를 못 쏘게 암호화 도장(SecOC)을 찍어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **차량 통신 선택 기준(Automotive Network Selection Criteria)**: 이 부품이 에어백인지 카메라 영상인지 파악해서 CAN, CAN FD, 이더넷 중 뭘 깔아줄지 결정하는 잔혹한 돈(TCO)과 대역폭 견적서이다.

</details>

- **차량 통신 선택 기준** 원칙에 따라 섀시 제어는 쥐어짜는 **캔 통신**(CAN), 고속 제어는 **캔 에프디**(CAN FD), ADAS 비전 백본은 **오토모티브 이더넷** 채택을 단호히 결정함

#### 한줄 요약

- 용량 적은 브레이크 제어는 CAN, 용량 큰 레이더는 CAN FD, 기가급 카메라는 오토모티브 이더넷으로 깔아라.
