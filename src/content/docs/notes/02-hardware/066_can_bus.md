## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **제어기 영역 네트워크(Controller Area Network, CAN)**: 여러 전자제어장치(Electronic Control Unit, ECU)가 공유 선로에서 방송하는 차량용 버스이다.
- **다중 마스터(Multi-master)**: 여러 노드가 중앙 제어기 없이 버스 사용을 요청하고 중재 결과에 따라 송신하는 구조이다.
- **비파괴 중재(Non-destructive Arbitration)**: 여러 노드가 동시에 송신해도 우선순위 승자의 프레임을 손상시키지 않는 중재 방식이다.

</details>

- 정의/개념: 여러 ECU가 차동 공유선에서 메시지 ID 우선순위로 **비파괴 중재**하는 **다중 마스터** 직렬 버스인 **CAN**이다.
- 배경/필요성: ECU가 늘어날수록 점대점 연결의 배선량과 커넥터 및 통합 비용이 급증하므로 공유 통신망이 필요하다.

#### 한줄 요약

- CAN은 메시지 ID 기반 **비파괴 중재**를 사용하는 다중 마스터 방송 버스이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **메시지 식별자(Message Identifier, ID)**: CAN 프레임의 의미와 버스 중재 우선순위를 나타내는 필드이다.
- **발행•구독(Publish•Subscribe)**: 송신자는 ID로 메시지를 방송하고 수신자는 필요한 ID만 필터링하는 통신 방식이다.
- **우성•열성 비트(Dominant•Recessive Bit)**: 여러 노드가 동시에 다른 비트를 보내면 우성 비트가 버스 값을 결정하는 신호 규칙이다.
- **최악 응답시간(Worst-case Response Time, WCRT)**: 메시지 송신 요청부터 중재와 전송을 마칠 때까지 걸리는 최대 시간이다.

</details>

- **메시지 ID 발행•구독**은 노드 주소 대신 메시지 의미를 기준으로 송수신자를 분리한다.
- **우성 비트 비파괴 중재**에서는 더 작은 수치의 ID가 우선권을 얻고 승자 프레임은 손상되지 않는다.
- 오류 검출과 카운터 및 버스 오프는 반복해서 오류를 일으키는 노드를 격리하여 정상 통신을 보호한다.

#### 한줄 요약

- CAN의 **WCRT**는 ID 우선순위와 버스 부하에 따라 결정되며, 오류 카운터는 고장 노드를 격리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **응용 소프트웨어(Application Software)**: 메시지 의미와 송신 주기 및 식별자를 설정하는 구성이다.
- **CAN 컨트롤러(CAN Controller)**: 메시지 프레임 생성과 수신 필터, 중재 및 오류 처리를 담당하는 장치이다.
- **CAN 트랜시버(CAN Transceiver)**: 컨트롤러의 논리 비트와 CAN 차동 선로의 전기 신호를 서로 변환하는 장치이다.
- **차동 버스•종단(Differential Bus•Termination)**: 메시지를 방송하고 양 끝의 저항으로 신호 반사를 억제하는 구성이다.

</details>

```text
[응용 소프트웨어] -- [CAN 컨트롤러] -- [CAN 트랜시버] -- [차동 버스•종단]
```

선의 의미: 응용 메시지 계층에서 프레임 제어, 전기 신호 변환, 공유 차동 선로까지 결합된 정적 CAN 노드 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 응용 소프트웨어 | 메시지•주기 설정 |
| CAN 컨트롤러 | 중재•오류 처리 |
| CAN 트랜시버 | 차동 신호 변환 |
| 차동 버스•종단 | 방송•반사 억제 |

#### 한줄 요약

- CAN 노드는 프레임 제어와 차동 신호 변환을 거쳐 공유 버스와 통신한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **경쟁 ID 비트열(Contending ID Bits)**: 여러 ECU가 중재 단계에서 동시에 버스에 내보내는 식별자 비트이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: CAN 프레임 전송 중 발생한 비트 오류를 검사값 비교로 검출하는 코드이다.
- **수신 확인(Acknowledgement, ACK)**: 하나 이상의 수신 노드가 프레임을 정상 수신했음을 우성 비트로 표시하는 필드이다.
- **ID 비트 중재**: 여러 ECU가 보낸 식별자 비트와 버스 값을 비교하는 단계이다.
- **중재 승패**: 열성 비트를 보낸 노드가 우성 비트를 읽으면 송신을 멈추는 단계이다.
- **승자 프레임**: 중재 승자가 데이터와 CRC를 포함한 나머지 프레임을 보내는 단계이다.
- **프레임 검증**: 수신 노드가 형식과 CRC를 확인하는 단계이다.
- **ACK·오류 플래그**: 정상 수신 또는 오류 검출 결과를 버스에 표시하는 단계이다.

</details>

```text
┌────────────── 보류 프레임 반복 ──────────────┐
│ 송신 ECU 집합          CAN 버스          수신 ECU 집합
│      │                    │                   │
│      ├─ 1. ID 비트 중재 ─►│                   │
│      │◄─ 2. 중재 승패 ────┤                   │
│      │                    │                   │
│      ├─ 3. 승자 프레임 ──►│──────────────────►│
│      │                    │                   │
│      │                    │   4. 프레임 검증  │
│      │                    │                   │
│      │                    │◄─ 5. ACK•오류 플래그
│      │◄──── 완료 또는 재전송 상태 ───────────┤
│      │                                        │
│      └── 패자는 버스 유휴 후 재중재 ─────────┘
└───────────────────────────────────────────────┘
```

### 동작 원리

1. **ID 비트 중재**: 여러 ECU가 **경쟁 ID 비트열**을 동시에 전송하면서 자신이 보낸 값과 버스 값을 비교한다.
2. **중재 승패**: 열성 비트를 보냈지만 우성 비트를 읽은 ECU는 송신을 중단하고, 더 작은 ID를 보낸 ECU가 우선권을 유지한다.
3. **승자 프레임**: 중재에서 이긴 ECU가 데이터와 CRC를 포함한 나머지 프레임을 전송한다.
4. **프레임 검증**: 수신 노드는 프레임 형식과 CRC를 검사하여 정상 수신 여부를 판단한다.
5. **ACK•오류 플래그**: 정상 수신 노드는 ACK를 보내고, 오류를 검출한 노드는 오류 플래그로 프레임을 중단시켜 재전송을 유도한다.

#### 한줄 요약

- **비파괴 중재**의 패자는 버스가 비면 다시 경쟁하고, 오류 프레임은 검출 후 재전송된다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **가변 데이터 전송률 CAN(CAN Flexible Data-rate, CAN FD)**: 64바이트 페이로드와 빠른 데이터 구간을 지원하는 규격이다.
- **자동차 이더넷(Automotive Ethernet)**: 스위치 기반 링크로 카메라와 백본의 대용량 데이터를 전송하는 차량 네트워크이다.
- **페이로드(Payload)**: 프레임의 식별자와 오류 제어 필드를 제외한 실제 응용 데이터이다.

</details>

| 차량 통신 방식 | CAN | CAN FD | 자동차 이더넷 |
|:---|:---|:---|:---|
| 적용 기준 | 차체•섀시의 짧은 제어 메시지 | 진단•센서•업데이트 데이터 | 카메라•백본의 대용량 데이터 |
| 핵심 특징 | **CAN**의 ID 우선순위 | **CAN FD**의 확장 **페이로드** | **자동차 이더넷**의 대용량 동시 전송 |
| 한계 | 낮은 우선순위 지연•대역폭 한계 | 기존 노드 호환성•비트 타이밍 검증 | 시간 동기•보안 구성 복잡 |

#### 한줄 요약

- 요구하는 **페이로드•대역폭**에 따라 CAN, CAN FD, 자동차 이더넷을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **버스 부하(Bus Load)**: 일정 시간 동안 CAN 버스가 프레임 전송으로 점유된 비율이다.
- **버스 오프(Bus-off)**: 송신 오류가 누적된 노드를 버스에서 분리하여 다른 통신을 보호하는 상태이다.
- **송신 오류 카운터(Transmit Error Counter, TEC)**: 송신 오류마다 증가하여 노드의 오류 상태와 버스 오프 전환을 결정하는 값이다.
- **메시지 인증 코드(Message Authentication Code, MAC)**: 비밀키와 메시지로 생성하여 송신자와 데이터 무결성을 검증하는 값이다.
- **신선도 값(Freshness Value)**: 메시지마다 증가하는 카운터나 시각 정보를 인증 범위에 포함하여 이전 메시지의 재전송을 식별하는 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **버스 부하**와 우선순위로 낮은 순위 ID가 계속 지연 | 최악 응답시간과 버스 부하 상한을 분석하고 ID를 재배정 | 각 메시지 데드라인 충족 |
| 물리 계층 오류가 누적되어 **버스 오프** 반복 | 배선•트랜시버와 **TEC** 증가 원인을 진단한 후 단계적으로 복귀 | 원인을 제거하면서 오류 격리 유지 |
| 종단•배선 오류로 신호 반사 증가 | 종단 저항•파형•토폴로지를 검증하고 허용 버스 길이 준수 | 신호 무결성을 확보해 프레임 오류율 감소 |
| ID만으로 송신자를 인증할 수 없어 위조•재전송 가능 | 게이트웨이 허용 목록과 **신선도 값**을 포함한 **MAC** 적용 | 비인가 송신과 재전송 공격 차단 |

#### 한줄 요약

- 긴급 메시지에는 **작은 ID**를 배정하고 WCRT와 버스 부하를 함께 검증해야 한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **짧은 제어 메시지(Short Control Message)**: 작은 페이로드를 정해진 주기와 데드라인에 맞춰 전달하는 차량 제어 데이터이다.
- **확장 데이터(Extended Data)**: 고전 CAN보다 큰 페이로드와 빠른 데이터 구간이 필요한 진단•센서•업데이트 정보이다.
- **대용량 데이터(High-volume Data)**: 영상처럼 CAN 계열의 대역폭을 넘어 스위치 기반 이더넷 전송이 필요한 데이터이다.
- **차량 통신 선택 기준**: 메시지의 크기와 데드라인 및 대역폭으로 CAN·CAN FD·자동차 이더넷을 고르는 기준이다.

</details>

- **차량 통신 선택 기준**에 따라 **짧은 제어 메시지**에는 **CAN**, **확장 데이터**에는 **CAN FD**, **대용량 데이터**에는 **자동차 이더넷**을 선택한다.

#### 한줄 요약

- CAN은 데드라인과 오류 격리를 만족해야 하는 짧은 제어 메시지에 적합하다.
