## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAN(Controller Area Network)**: 차량 및 산업용 기기에서 호스트 컴퓨터 없이 ECU들이 2선식 차동 버스를 통해 고신뢰 통신을 수행하도록 제정된 표준 (ISO 11898).
- **Multi-Master(다중 마스터)**: 마스터-슬레이브 구조와 달리 버스가 유휴 상태일 때 모든 노드가 자율적으로 메시지 전송을 시작할 수 있는 구조.
- **Non-Destructive Arbitration(비파괴 중재)**: 여러 노드가 동시 송신 시 우선순위가 높은 메시지의 데이터 손실이나 지연 없이 낮은 우선순위 노드만 조용히 전송을 양보하는 충돌 해결 기법.

</details>

- 정의/개념: 차량 내 전자제어장치(ECU) 간 2선식 꼬임 차동 신호선(CAN-H, CAN-L) 상에서 메시지 식별자(ID) 기반의 비파괴 비트 단위 중재(CSMA/CD+NBA)를 수행하는 다중 마스터 직렬 버스 통신 표준 (ISO 11898)
- 배경/필요성: 차량 전장 부품 증가에 따른 점대점 배선 하네스(Wire Harness)의 무게 및 비용을 획기적으로 줄이고, **열악한 전자기 간섭(EMI) 환경에서 높은 신뢰성과 실시간 제어 메시지 전송 보장**

#### 한줄 요약

- 2선식 차동 신호선 기반의 **메시지 ID 우선순위 비파괴 중재 및 고신뢰 차량 통신 표준**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Dominant Bit(우성 비트, 논리 0)**: 전기적으로 버스 전압 차이를 발생시켜 열성 비트(논리 1)를 덮어쓰고 중재에서 승리하는 비트.
- **Recessive Bit(열성 비트, 논리 1)**: 버스 라인이 수동 상태일 때 나타나며, 우성 비트와 충돌 시 밀려나는 비트.
- **Bus-Off(버스 오프)**: 전송 오류 카운터(TEC)가 255를 초과한 결함 노드가 전체 버스를 마비시키지 않도록 하드웨어적으로 버스 연결을 강제 분리하는 격리 상태.

</details>

- 노드 주소가 아닌 메시지 내용 식별자(ID)를 기반으로 모든 노드가 청취하는 **발행-구독(Publish-Subscribe) 방송 구조**
- 버스 상에서 우성 비트(0)가 열성 비트(1)를 덮어씌워 ID 숫자가 낮을수록 우선순위를 획득하는 **비파괴 비트 단위 중재(Wired-AND 논리)**
- 오류 카운터(TEC/REC) 기반으로 결함 노드를 자율 격리하는 **3단계 결함 봉쇄(Error-Active $\to$ Error-Passive $\to$ Bus-Off)**

#### 한줄 요약

- **비파괴 비트 단위 중재(Dominant 0 우선)·메시지 지향 방송(Pub/Sub)·하드웨어 결함 격리(Bus-Off)**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAN Controller**: 프레임 패킹, 비트 스터핑, CRC 계산, 중재 및 에러 검출을 수행하는 디지털 로직 IP.
- **CAN Transceiver**: 디지털 로직 레벨 신호(TxD/RxD)를 물리 차동 전압(CAN-H, CAN-L)으로 상호 변환하는 아날로그 PHY 칩.
- **120Ω Termination Resistor**: 버스 양 끝단에 설치되어 고속 신호 전송 시 전송선 끝에서 반사파(Signal Reflection)가 발생하는 것을 흡수하는 종단 저항.

</details>

```text
[ CAN 통신 노드 및 2선식 차동 버스 아키텍처 ]
┌──────────────────────────────┐        ┌──────────────────────────────┐
│ ECU 노드 1                   │        │ ECU 노드 2                   │
│  ├─ 제어용 응용 마이크로컨트롤러│        │  ├─ 제어용 응용 마이크로컨트롤러│
│  ├─ CAN 컨트롤러 (TxD / RxD) │        │  ├─ CAN 컨트롤러 (TxD / RxD) │
│  └─ CAN 트랜시버 (CAN-H/L)   │        │  └─ CAN 트랜시버 (CAN-H/L)   │
└──────────────┬───────────────┘        └──────────────┬───────────────┘
               │                                       │
 [120Ω 종단] ══╧══════════════ CAN-H (2.5V ~ 3.5V) ═══╧══════════════ [120Ω 종단]
 [저항 장착] ══╤══════════════ CAN-L (2.5V ~ 1.5V) ═══╤══════════════ [저항 장착]
```

선의 의미: 응용 SW, CAN 컨트롤러, CAN 트랜시버, 차동 버스선(CAN-H/L) 및 120Ω 종단 저항 간의 CAN 통신 노드 계층 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 응용 소프트웨어 | 브레이크를 밟았는지 판단하고, "가장 급함(작은 ID)" 번호표를 할당해 메시지 박스에 밀어 넣는 앱 |
| 캔 컨트롤러 | 번호표를 보고 순서를 정하며, 에러가 났는지(CRC) 깐깐하게 검사하는 뇌하수체 논리 칩셋 |
| 캔 트랜시버 | 컨트롤러의 약해 빠진 디지털 신호를 자동차의 험악한 노이즈를 뚫을 수 있는 강력한 차동 전압(CAN-H/L)으로 뻥튀기하는 근육 |
| 차동 버스 종단 | 꼬임선으로 노이즈를 서로 씹어먹고 상쇄하며, 양 끝에 120옴(Ω) 저항을 달아 신호 반사파 튕김을 억제하는 전송 도로 |

#### 한줄 요약

- **응용 소프트웨어·CAN 컨트롤러(MAC/LLC)·CAN 트랜시버(PHY)·차동 버스선(120Ω 종단)**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Bit Stuffing(비트 스터핑)**: 클록 동기화를 유지하기 위해 동일한 비트가 연속으로 5개 나타나면 반대 극성의 보조 비트를 1개 강제 삽입하는 하드웨어 규칙.

</details>

```text
[ CAN 버스 비파괴 중재 및 프레임 전송 시퀀스 ]
                         │
                         ▼
   [ 1. 버스 유휴(Idle) 상태 감지 후 복수 노드가 SOF 및 ID 비트 동시 송출 ]
                         │
                         ▼
   [ 2. 비트 단위 중재 : 자신이 송출한 비트와 버스 전압(RxD) 비교 모니터링 ]
                         │
        +─────────────────────────────────────────+
        │    [ 송출 비트(1, 열성) != 버스 비트(0, 우성)? ]
        │    /                                   \
        │ [ 예 (중재 패배) ]                  [ 아니오 (중재 승리) ]
        │   │                                      │
        │ 3. 즉각 송신 중단 및               4. 전체 프레임(Data/CRC)
        │    수신 모드로 전환                   무손실 연속 송신 지속
        +─────────────────────────────────────────+
                         │
                         ▼
   [ 5. 모든 수신 노드가 CRC 검증 후 정상 시 ACK 슬롯에 우성(0) 응답 기록 ]
```

**동작 원리**

1. **동시 전송 시작**: 버스가 3비트 이상 비어있을 때 여러 노드가 Start of Frame(SOF)을 쏘고 메시지 ID 송출
2. **비트 비교 모니터링**: 각 노드는 송출과 동시에 버스 전압을 피드백 읽어 자신이 보낸 비트와 일치하는지 검사
3. **중재 패배 및 양보**: 1(열성)을 송출했으나 타 노드가 0(우성)을 쏴서 버스가 0이 되면 즉각 송신을 포기하고 수신 전환
4. **승자 무손실 완주**: 가장 낮은 ID를 가진 노드가 1비트의 지연이나 프레임 손실 없이 전체 데이터와 CRC 송출
5. **ACK 응답**: 프레임을 정상 수신한 모든 노드가 ACK 슬롯 비트에 우성(0)을 덮어써 수신 완료 확인

#### 한줄 요약

- 버스 유휴 감지 $\to$ **동시 ID 비트 송출 $\to$ 우성(0) 승자 전송 지속 & 열성(1) 패자 즉시 수신 전환 $\to$ CRC 검증 $\to$ 수신 노드 ACK 응답**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Classical CAN vs CAN FD vs Automotive Ethernet**:
  - Classical CAN: 최대 1Mbps, 8B 페이로드, 차체/섀시 기본 제어
  - CAN FD: 최대 5+Mbps, 64B 페이로드, 파워트레인/ADAS 센서
  - Automotive Ethernet: 100M~1Gbps+, IP 패킷, 자율주행 라이다/비전 백본

</details>

| 비교 항목 | Classical CAN (CAN 2.0B) | CAN FD (Flexible Data-Rate) | Automotive Ethernet (100/1000BASE-T1) |
|:---|:---|:---|:---|
| 최대 대역폭 및 페이로드 | 최대 1 Mbps, 최대 8 바이트 | 중재 1 Mbps / 데이터 2~5+ Mbps, 최대 64 바이트 | 100 Mbps ~ 1 Gbps+, 수천 바이트 (IP 패킷) |
| 버스 토폴로지 및 중재 | 2선식 공유 버스, 비파괴 비트 중재 | 2선식 공유 버스, 비파괴 비트 중재 | 점대점(P2P) 스타형, 스위치 패킷 라우팅 |
| 한계 및 적합 분야 | 대용량 데이터 전송 한계 (차체/섀시 제어) | 레거시 CAN 혼용 시 호환 제약 (파워트레인/ADAS) | 스위치 단가 및 소비 전력 증가 (자율주행 비전/백본) |

#### 한줄 요약

- 기본 제어는 **Classical CAN**, 고속 전장은 **CAN FD**, 초고속 ADAS 백본은 **Automotive Ethernet**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Bus Load(버스 부하율)**: CAN 버스의 단위 시간당 가동 비율로, 최악 응답시간(WCRT) 보장을 위해 보통 70% 이하(안전 기준 50% 권장)로 설계.
- **SecOC(Secure Onboard Communication)**: AUTOSAR 표준 보안 모듈로 CAN 메시지마다 MAC(메시지 인증 코드)과 신선도 값(Freshness Value)을 실어 스푸핑/재전송 공격을 방어.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 똥차들이 버스를 점령해서(**버스 부하** 폭발) 덜 중요한 메시지가 평생 못 나가고 썩어버리는 무한 지연 셧다운 사태 | 메시지 ID를 뼛속까지 뜯어고쳐 우선순위를 칼같이 재배정하고, 전체 부하 상한선을 깐깐하게 강제 통제 | 아무리 차가 막혀도 에어백 터뜨리는 메시지만큼은 무조건 제시간(**최악 응답 시간**)에 뚫고 나가는 생존 보장 |
| 비가 오거나 엔진 스파크가 튀어서 특정 칩이 미쳐 날뛰며 에러를 뿜어내 버스 전체를 마비시키는 연쇄 참사 발발 | 에러를 계속 뿜어내는 놈을 카운팅(TEC)하다가 한계치(255)를 넘으면 물리 선에서 강제로 쫓아냄(**버스 오프**) | 고장 나서 미쳐 날뛰는 칩 하나 때문에 버스 전체가 셧다운되는 최악의 연쇄 폭발 사태 원천 차단 |
| 해커가 외부에서 "브레이크 밟아!"라는 가짜 CAN 메시지를 몰래 쑤셔 넣어 운전자를 죽이는 스푸핑 끔찍한 공격 | AUTOSAR **시큐어 온보드 커뮤니케이션**(SecOC) 규격을 떡칠하여 메시지 끝에 암호화 인증 도장(MAC)을 강제 부여 | 메시지 위변조 및 어제 보낸 메시지를 오늘 다시 쏘는 기만적인 재전송(Replay) 해킹 공격 100% 얄짤없이 방어 |

#### 한줄 요약

- **WCRT 분석 및 버스 부하율(70% 이하) 통제·TEC/REC 결함 노드 Bus-Off 자동 격리·AUTOSAR SecOC 보안**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **CAN XL (차세대 표준)**: 최대 20Mbps 속도와 2048 바이트 페이로드를 지원하여 CAN FD와 Ethernet 간의 간극을 메우는 3세대 CAN 표준.

</details>

- 차량용 E/E 아키텍처에서 **도메인/존(Zone) 제어기 내부 통신은 CAN FD 표준 채택 및 고용량 센서 백본에 Automotive Ethernet 결합 적용**

#### 한줄 요약

- **메시지 주기와 대역폭, 기능 안전(ISO 26262)** 요구에 따른 차량 통신망 계층화
