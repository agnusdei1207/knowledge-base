## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding/Bypassing)**: 선행 명령어의 연산 결과를 레지스터 파일에 기록(WB)하기 전에 후속 명령어의 실행(EX) 단계 입력으로 직접 우회 전달하여 RAW 데이터 스톨을 방지하는 하드웨어 기법.
- **분기 예측(Branch Prediction)**: 조건부 분기 명령어의 실행 결과가 확정되기 전에 분기 방향(Taken/Not-Taken)과 목표 주소를 미리 추측하여 명령어 인출의 연속성을 보장하는 기법.
- **파이프라인 스톨(Pipeline Stall)**: 데이터 의존성이나 분기 지연으로 인해 파이프라인 단계의 전진을 멈추고 버블(NOP)을 삽입하는 제어 동작.

</details>

- 정의/개념: 선행 연산 결과를 레지스터 파일에 쓰기 전에 후속 연산 입력으로 직접 바이패스하는 **포워딩**과 분기 판정 전 목표 주소로 사전 인출하는 **분기 예측**을 결합하여 파이프라인 지연을 최소화하는 프로세서 성능 최적화 기법
- 배경/필요성: 파이프라인 해저드 발생 시 단순 스톨 삽입에 따른 클록당 명령어 수(IPC) 급감과 파이프라인 중첩 이득 상쇄를 방어하기 위한 하드웨어 바이패스 및 투기적 사전 인출 체계 확립

#### 한줄 요약
- 포워딩은 데이터 의존성 대기를 하드웨어 바이패스로 제거하고, 분기 예측은 제어 흐름 단절을 투기적 인출로 극복한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 로드 결과 준비 전에 후속 명령어가 값을 요구해 포워딩만으로 해소되지 않을 수 있는 데이터 해저드.
- **분기 오예측(Branch Misprediction)**: 예측한 분기 방향 또는 목표 주소가 실제 실행 결과와 불일치하여 잘못 인출된 파이프라인 단계를 모두 비워야 하는 상태.
- **플러시 페널티(Flush Penalty)**: 분기 오예측 시 잘못 진입된 파이프라인 레지스터들을 NOP으로 무효화하고 올바른 주소에서 재인출하는 데 소요되는 손실 클록 사이클.

</details>

- 데이터 지연 완화: **포워딩**으로 준비된 ALU 결과를 후속 EX 입력에 전달해 RAW 스톨 감소(**적재-사용 의존**은 1사이클 스톨 후 포워딩)
- 제어 지연 은닉: **분기 예측**을 기반으로 분기문 판정 전에 다음 명령어를 지속 인출하여 제어 해저드에 의한 파이프라인 공백 차단
- 오예측 손실 관리: **분기 오예측** 발생 시 **플러시 페널티**가 발생하므로 예측 정확도 향상 회로(BHT/BTB) 필수

#### 한줄 요약
- 포워딩은 준비된 값을 우회하고, 분기 예측은 적중한 경로의 제어 지연을 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 유닛(Forwarding Unit)**: EX/MEM 및 MEM/WB 파이프라인 레지스터의 목적 레지스터 번호와 현재 ID/EX의 소스 레지스터 번호를 비교하여 우회 멀티플렉서를 제어하는 회로.
- **우회 멀티플렉서(Bypass MUX)**: 레지스터 파일에서 읽어온 원본 데이터와 EX/MEM, MEM/WB 단계에서 우회된 최신 데이터 중 올바른 피연산자를 선택하는 하드웨어 회로.
- **분기 이력 테이블(Branch History Table, BHT)**: 과거 분기 실행 이력을 2비트 포화 카운터 등으로 기록하여 분기 방향(Taken/Not-Taken)을 예측하는 하드웨어 테이블.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 명령어의 주소를 태그로 사용하여 과거에 계산된 분기 목표 주소를 캐싱하고 IF 단계에서 즉시 다음 PC로 제공하는 캐시.

</details>

```text
+-----------------------------------------------------------------------+
| 파이프라인 포워딩 및 분기 예측 마이크로아키텍처                       |
|                                                                       |
|  [프론트엔드: 분기 예측 서브시스템]                                   |
|  +-----------------------------------------------------------------+  |
|  |  +--------------------+     +--------------------+              |  |
|  |  | 분기 이력 테이블   |     | 분기 대상 버퍼     |==> 다음 PC 공급|  |
|  |  | (BHT: 2비트 카운터)|     | (BTB: 목표 주소 캐시)|   (IF 단계)   |  |
|  |  +--------------------+     +--------------------+              |  |
|  +-----------------------------------------------------------------+  |
|                                                                       |
|  [백엔드 데이터패스: 포워딩 서브시스템]                               |
|  +-----------------------------------------------------------------+  |
|  |  +---------------------+      바이패스 데이터 버스+---------------+  |  |
|  |  | 우회 MUX / EX (ALU) |<=========================| EX/MEM, MEM/WB|  |  |
|  |  +----------^----------+                          +---------------+  |  |
|  |             | 바이패스 제어 신호                                  |  |
|  |  +----------+----------+                                          |  |
|  |  | 포워딩 유닛         | (레지스터 번호 비교 및 소스 선택 MUX 제어)|  |
|  |  +---------------------+                                          |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

선의 의미: `+---+`는 예측기 및 데이터패스 기능 경계, `<==`는 연산 결과 바이패스 데이터 버스, `->`는 제어 신호 흐름

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 유닛 | 파이프라인 레지스터와 소스 레지스터 주소 비교 및 **우회 경로 제어** |
| 우회 멀티플렉서 | 레지스터 원본 값과 바이패스 최신 연산값 중 **유효 피연산자 선택** |
| 분기 이력 테이블(BHT) | 2비트 포화 카운터 기반 분기 방향(Taken/Not-Taken) **확률적 예측** |
| 분기 대상 버퍼(BTB) | 분기 목표 주소를 고속 캐싱하여 IF 단계에 **차기 PC 즉시 공급** |
| 플러시 제어 회로 | 분기 오예측 확정 시 잘못 진입된 파이프라인 명령어 **무효화 및 PC 복구** |

#### 한줄 요약
- 포워딩 서브시스템은 ALU 입력단에서 데이터 의존성을 즉시 풀고, 분기 예측 서브시스템은 프론트엔드에서 다음 실행 경로를 연속 공급한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 레지스터에 쓰기 전에 후속 명령어가 해당 레지스터를 읽으려 할 때 발생하는 진성 데이터 의존성.

</details>

```text
[명령어 파이프라인 실행 중 해저드 제어 흐름]
                       │
                       ▼
         1. 해저드 요인 및 명령어 유형 식별
            ┌──────────┴──────────┐
    (RAW 데이터 의존성)     (조건부 분기 명령어)
            │                     │
            ▼                     ▼
     2. 포워딩 경로 활성화  3. BHT/BTB 투기적 인출
     (EX 입력 직접 바이패스) (IF 단계 다음 PC 공급)
            │                     │
            │                     ▼
            │               4. 분기 조건 확정 및 검증
            │                ┌────┴────┐
            │             (일치)    (오예측)
            │                │         │
            │                │         ▼
            │                │   5. 오예측 플러시 및 복구
            │                │   (IF/ID NOP 및 주소 재인출)
            └────────┬───────┴─────────┘
                     │
                     ▼
[정합성 유지 상태에서 파이프라인 정상 전진 지속]
```

분기 결과: **포워딩**은 즉시 데이터를 공급하여 파이프라인을 유지하며, **분기 예측**은 적중 시 지연이 없으나 오예측 시 플러시 페널티를 치르고 복구함

**동작 원리**

1. **해저드 요인 및 명령어 유형 식별**: 매 클록 사이클마다 프론트엔드에서 분기 명령어 여부를, 백엔드에서 소스-목적 레지스터 번호 일치 여부를 동시 판별함
2. **포워딩 경로 활성화**: ALU 연산 간 RAW 데이터 의존성 감지 시 포워딩 유닛이 바이패스 MUX를 구동하여 직전 파이프라인 레지스터 값을 즉시 공급함
3. **BHT/BTB 투기적 인출**: 분기 명령어 인출 시 BHT 및 BTB를 조회하여 분기 성립을 예측하고 파이프라인 중단 없이 후속 명령어를 연속 인출함
4. **분기 조건 확정 및 검증**: EX 단계에서 분기 ALU 결과가 확정되면 예측기와 실제 결과를 대조하여 일치 시 무지연 전진을 지속함
5. **오예측 플러시 및 복구**: 분기 예측 실패 확정 시 파이프라인 플러시 회로가 IF/ID 단계의 투기적 명령어를 NOP으로 무효화하고 정정된 주소로 재인출함

#### 한줄 요약
- 포워딩은 EX 단계에서 즉시 우회하고, 분기 예측은 IF 단계에서 추측 인출한 후 EX 단계에서 검증 및 복구한다.

## Ⅴ. 종류 및 비교

| 파이프라인 최적화 기법 | 데이터 포워딩 (Forwarding) | 동적 분기 예측 (Dynamic Branch Prediction) |
|:---|:---|:---|
| 적용 기준 | **연산 결과 데이터 의존성(RAW)** 해소 요구 | **조건부 분기문 실행 지연** 해소 요구 |
| 핵심 특징 | **우회 멀티플렉서** 기반 연산값 직접 전달 | **BHT·BTB** 기반 투기적 연속 인출 |
| 한계 | 로드-사용 의존성 시 불가피한 1스톨 발생 | 오예측 시 파이프라인 깊이만큼 **플러시 페널티** 발생 |

#### 한줄 요약
- 포워딩은 연산 결과가 나오는 순간 즉시 가로채어 전달하는 결정론적 기법이며, 분기 예측은 과거 이력을 기반으로 미래 경로를 추측하는 확률적 기법이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 스케줄링(Instruction Scheduling)**: 컴파일러가 의존성 관계를 분석하여 적재-사용 스톨 구간에 독립적인 명령어를 재배치하는 최적화 기법.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차적으로 실행된 명령어의 결과를 프로그램 원래 순서대로 안전하게 커밋하는 원형 큐 구조.
- **TAGE(TAgged GEometric history length predictor)**: 서로 다른 길이의 글로벌 분기 이력을 태그 매칭하여 복합 분기 패턴을 고정밀 예측하는 하드웨어 분기 예측기.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적재-사용 의존으로 인한 포워딩 경로 1사이클 지연 | 컴파일러 **명령어 스케줄링** 및 비순서 실행(OoO) 적용 | 독립 연산 재배치를 통한 대기 슬롯 완전 은닉 |
| 깊은 파이프라인 구조에서 오예측 시 플러시 페널티 급증 | 다중 이력 기반 **TAGE 분기 예측기** 도입 | 복합 루프 예측 적중률 97% 이상 달성 및 플러시 억제 |
| 투기적 실행 결과가 잘못 노출되어 프로세서 상태 오염 위험 | **재주문 버퍼(ROB)** 기반 인오더 커밋(In-Order Commit) 강제 | 오예측 시 미커밋 명령어를 일괄 롤백하여 예외 정합성 유지 |

#### 한줄 요약
- 포워딩의 한계는 컴파일러 스케줄링으로 보완하고, 분기 예측의 플러시 위험은 TAGE 예측기와 ROB 순차 커밋으로 통제한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **퍼셉트론 분기 예측기(Perceptron Branch Predictor)**: 단일 신경망 인공 뉴런(퍼셉트론)의 가중치 합산 연산을 통해 긴 분기 이력의 상관관계를 학습·예측하는 인공지능 기반 분기 예측 구조.
- **스펙터(Spectre)**: 분기 예측기의 투기적 실행 과정에서 발생하는 마이크로아키텍처 부채널(캐시 상태 등)을 악용하여 격리된 기밀 메모리를 탈취하는 하드웨어 취약점.

</details>

- 하드웨어 포워딩과 고정밀 분기 예측(TAGE)은 파이프라인 효율을 지탱하는 표준 기술로 확립되었으며, 차세대 마이크로아키텍처에서는 신경망 기반 **퍼셉트론 예측기**와 투기적 실행 보안 취약점(**Spectre**) 방어 하드웨어 격리 기제로 진화하고 있어, 분기 예측기 테이블 크기·바이패스 버스 면적 오버헤드와 IPC 개선율 간 상충을 정량 분석한 회로 구성 설계

#### 한줄 요약
- 포워딩과 분기 예측은 파이프라인 성능을 완성하는 양대 축이며, 하드웨어 우회와 고정밀 예측의 융합이 핵심이다.
