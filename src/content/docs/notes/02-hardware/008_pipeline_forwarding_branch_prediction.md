## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding/Bypassing)**: 연산 결과를 레지스터에 기록하기 전 후속 명령어의 입력으로 직접 전달하여 대기 사이클을 제거하는 기법.
- **분기 예측(Branch Prediction)**: 조건 분기의 방향과 목표 주소를 사전에 추정하여 명령어 인출을 중단 없이 지속하는 기술.
- **파이프라인 스톨(Pipeline Stall)**: 의존성이나 분기 미확정으로 인해 명령어를 진행하지 못하고 유휴 대기하는 상태.

</details>

- 정의/개념: 데이터 해저드의 쓰기 지연을 우회 전송하는 포워딩(Bypassing)과 제어 해저드의 분기 지연을 사전 추정하는 분기 예측(Branch Prediction) 기법
- 배경/필요성: 깊은 파이프라인에서 급증하는 스톨(Stall) 및 플러시(Flush) 페널티를 은닉하고 **프로세서 IPC(Instructions Per Cycle) 성능 극대화**

#### 한줄 요약

- **결과 우회(포워딩)**와 **사전 경로 추정(분기 예측)**으로 파이프라인 스톨 최소화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **분기 오예측(Branch Misprediction)**: 추정된 분기 방향이 실제 연산 결과와 일치하지 않는 오류 상태.
- **플러시 페널티(Flush Penalty)**: 오예측 시 잘못 인출된 명령어들을 파이프라인에서 비우고 올바른 경로를 재인출하는 클록 손실.

</details>

- **포워딩** 기법을 통한 이전 단계 연산 결과의 후속 연산기 입력 즉시 우회 전송
- **분기 예측** 기법을 통한 분기 타깃 사전 추정 및 명령어 인출 단절 방지
- **분기 오예측** 발생 시 파이프라인 깊이에 비례한 **플러시 페널티** 발생 통제

#### 한줄 요약

- 포워딩과 분기 예측으로 대기를 줄이나, **오예측 시 플러시 페널티** 수반

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 제어기(Forwarding Unit)**: 소스 레지스터와 목적 레지스터 번호를 실시간 비교하여 우회 MUX 선택 신호를 생성하는 회로.
- **BHT(Branch History Table)**: 과거 분기 실행 이력을 바탕으로 분기 방향(Taken / Not Taken)을 예측하는 2-bit 포화 카운터 테이블.

</details>

```text
[ 데이터 및 제어 경로 최적화 구조 ]
 ├─ 데이터 해저드 경로
 │  ├─ 파이프라인 레지스터 (EX/MEM, MEM/WB)
 │  ├─ 포워딩 제어기 (Forwarding Unit)
 │  └─ 우회 다중화기 (Bypass MUX)
 └─ 제어 해저드 경로
    ├─ 분기 예측기 (BHT, Branch History Table)
    ├─ 분기 타깃 버퍼 (BTB, Branch Target Buffer)
    └─ 복구 로직 (Pipeline Flush & PC Redirect)
```

선의 의미: 포워딩 제어기/우회 MUX와 분기 예측기/복구 로직으로 구성된 하드웨어 최적화 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 제어기 | 레지스터 비교로 우회 신호 생성 |
| 우회 다중화기 | 레지스터 값과 우회 값 중 연산기 입력 선택 |
| 분기 예측기 | 예측 테이블 기반 방향 및 타깃 주소 산출 |
| 복구 로직 | 오예측 시 파기 및 복구 제어 수행 |

#### 한줄 요약

- **포워딩 MUX** 기반 데이터 우회와 **BHT/BTB** 기반 제어 흐름 추정

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **적재-사용 스톨(Load-Use Stall)**: 메모리 읽기 데이터가 MEM 단계가 끝나야 나오므로 1클록 스톨 후 포워딩해야 하는 현상.

</details>

```text
[ 명령어 해독 및 의존성 평가 ]
        │
        ├─ 데이터 해저드 ──> [ 포워딩 다중화기 제어 ]
        │                    └─ 적재-사용 지연 시 1클록 대기 후 포워딩
        │
        └─ 제어 해저드 ───> [ 동적 분기 예측기(BHT/BTB) 가동 ]
                             ├─ 예측 성공 : 정지 없는 연속 명령어 인출
                             └─ 예측 실패 : 조건 연산 단계에서 파이프라인 플러시 후 복구
```

**동작 원리**

1. **의존성 검출**: 해독(ID) 단계에서 소스 레지스터와 이전 명령의 목적 레지스터 일치 여부 판별
2. **포워딩 실행**: EX/MEM 또는 MEM/WB 단계의 결과를 ALU 입력 MUX로 우회 전달 (Load-Use 시 1클록 스톨 주입)
3. **분기 예측**: BHT 카운터와 BTB 캐시를 참조하여 다음 PC 주소를 추정하고 연속 인출 수행
4. **오예측 복구**: 실제 분기 조건 판정 결과 불일치 시 잘못 진입한 명령어 플러시 및 정상 주소 재인출

#### 한줄 요약

- 데이터는 **우회 MUX 선택**, 분기는 **예측 실행 후 오예측 시 플러시 복구**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RAW vs Branch Penalty**: RAW 데이터 의존성은 포워딩으로 거의 은닉 가능하나, 분기 오예측은 파이프라인 플러시 손실 발생.

</details>

| 비교 항목 | 데이터 포워딩 (Forwarding) | 동적 분기 예측 (Branch Prediction) |
|:---|:---|:---|
| 적용 기준 | 선행-후속 명령어 간 RAW 데이터 의존성 발생 시 | 조건 분기문(if-else, loop)에 따른 제어 지연 발생 시 |
| 핵심 특징 | EX/MEM, MEM/WB 레지스터 결과를 ALU 입력으로 직접 우회 | 2-bit 포화 카운터(BHT) 및 타깃 버퍼(BTB) 기반 사전 인출 |
| 한계 및 위험 | Load-Use 해저드 시 1사이클 스톨 불가피 | 오예측(Misprediction) 발생 시 파이프라인 플러시 페널티 부과 |

#### 한줄 요약

- 포워딩은 **연산 결과 즉시 우회**, 분기 예측은 **경로 선제 인출**로 지연 제거

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ROB(Reorder Buffer)**: 비순차 실행 환경에서 추측 실행된 명령어들을 원래 프로그램 순서대로 커밋(Commit)하여 아키텍처 상태를 정밀하게 보존하는 버퍼.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **적재-사용 의존성** 발생에 따른 지연 | 컴파일러 기반 **명령어 재배치** 적용 | 하드웨어 대기 시간을 은닉하여 성능 유지 |
| 잦은 오예측으로 인한 파기 손실 누적 | 대규모 고급 분기 예측기 도입 및 용량 확장 | 타깃 예측 정확도 대폭 향상 |
| 오예측 경로 명령어 실행에 따른 레지스터 상태 오염 | **재주문 버퍼** 적용을 통한 상태 반영 제어 | 안전하고 정밀한 하드웨어 상태 보존 |

#### 한줄 요약

- **명령어 스케줄링·고급 분기 예측·재주문 버퍼(ROB)**로 안정적 성능 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **토너먼트 분기 예측기**: 지역 예측기와 전역 예측기를 조합하여 분기 유형에 따라 최적의 예측기를 동적으로 선택하는 고급 예측 아키텍처.

</details>

- 데이터 대기 병목에는 **포워딩 및 컴파일러 스케줄링**, 분기 손실에는 **동적 분기 예측 및 ROB** 적용

#### 한줄 요약

- **해저드 유형별 특화 기법** 적용을 통한 프로세서 처리율 극대화
