## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **포워딩**: 앞 명령의 결과를 레지스터 기록 전에 후속 명령의 실행 입력으로 직접 전달하여 데이터 대기를 줄이는 기법이다.
- **분기 예측**: 분기 결과가 확정되기 전에 방향과 대상 주소를 추정하여 명령어 인출을 계속하는 기법이다.
- **버블**: 데이터나 제어 대기로 유효한 명령이 처리되지 않는 빈 파이프라인 주기이다.
- **명령어당 사이클 수(Cycles Per Instruction, CPI)**: 명령어 하나를 완료하는 데 필요한 평균 클록 수이다.

</details>

- 정의/개념: **포워딩**과 **분기 예측**은 결과 우회와 예측 경로 선인출로 파이프라인 대기를 줄이는 해저드 완화 기법이다.
- 배경/필요성: 레지스터 기록•분기 확정까지 기다리면 **버블**이 늘어 **CPI**가 상승한다.

#### 한줄 요약
- 포워딩은 데이터 대기를 줄이고 분기 예측은 제어 대기를 줄여 평균 CPI를 낮춘다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **분기 오예측**: 예측한 방향이나 대상이 실제 결과와 달라 이미 인출한 명령어를 폐기해야 하는 상황이다.
- **플러시 패널티**: 분기 오예측 시 이미 인출/해석된 오경로 명령어를 무효화(Flush)하고 올바른 주소에서 재인출하는 동안 발생하는 사이클 손실이다.

</details>

- **포워딩**으로 기록 전 선행 결과를 후속 실행 입력에 전달한다.
- **분기 예측**으로 분기 확정 전 예상 경로의 인출 지속이 핵심이다.
- 분기 판정이 늦을수록 **플러시 패널티**와 복구 주기가 증가한다.
- **분기 오예측**이 반복되면 경로 복구 비용이 누적된다.

#### 한줄 요약
- 포워딩은 확정값을 우회하고 분기 예측은 미확정 경로를 추정하므로 오예측에만 복구 비용이 발생한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **포워딩 장치**: 인접 명령의 레지스터 번호를 비교하여 실행 입력의 우회 여부를 결정하는 회로이다.
- **우회 선택기**: 레지스터 값과 앞 단계의 실행 결과 중 실행부에 공급할 값을 선택하는 회로이다.
- **복구 로직**: 오예측 명령을 무효화하고 프로그램 카운터를 올바른 주소로 되돌리는 회로이다.
- **분기 예측기**: 분기의 과거 이력 등을 이용해 다음 방향과 대상 주소를 추정하는 회로이다.
- **인출 제어기**: 예측 주소나 복구 주소를 프로그램 카운터에 반영해 다음 명령을 가져오는 회로이다.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어 주소를 보관하는 레지스터이다.
- **PC 복원**: 오예측 뒤 PC를 실제 분기 경로의 주소로 되돌리는 동작이다.

</details>

```text
파이프라인 해저드 완화 회로
├─ 데이터 경로 제어
│  ├─ 포워딩 장치
│  └─ 우회 선택기
└─ 제어 경로 관리
   ├─ 분기 예측기
   ├─ 인출 제어기
   └─ 복구 로직
```

가지의 의미: 데이터 우회와 분기 예측•복구의 정적 책임 구분이다.

| 구성요소 | 책임 |
|:---|:---|
| **포워딩 장치** | 의존 비교와 우회 선택 신호 생성 |
| **우회 선택기** | 실행부의 피연산자 출처 선택 |
| **분기 예측기** | 분기 방향과 대상 주소 추정 |
| **인출 제어기** | 예측•복구 주소의 명령어 인출 |
| **복구 로직** | 오경로 무효화와 **PC 복원** |

#### 한줄 요약
- 포워딩 장치가 준비된 값을 우회하고 분기 예측기와 복구 로직이 추측 경로를 관리한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **분기 이력**: 과거 분기의 실제 방향을 저장하여 이후 분기 예측의 근거로 사용하는 정보이다.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 명령과 대상 주소를 저장하는 예측용 버퍼이다.
- **플러시**: 오예측 경로에서 인출한 명령을 무효화하고 올바른 주소부터 다시 채우는 동작이다.
- **쓰기 후 읽기(Read After Write, RAW) 데이터 해저드**: 앞 명령의 기록 전에 후속 명령이 같은 위치를 읽는 충돌이다.
- **BTB 갱신**: 실제 분기 대상 주소를 분기 대상 버퍼에 반영해 이후 예측에 사용하는 동작이다.
- **Load-Use 스톨**: 메모리 읽기 완료 시점(MEM 단계)이 후속 명령의 실행 시점(EX 단계)보다 늦어 포워딩으로도 1사이클 지연이 발생하는 파이프라인 정체이다.
- **해저드 판정**: 레지스터 의존과 미확정 분기 여부를 식별하는 단계이다.
- **결과 준비 판정**: 선행 결과를 우회할 수 있는지 확인해 포워딩 또는 스톨을 정하는 단계이다.
- **예측 경로 인출**: 분기 이력과 BTB로 예상한 주소에서 후속 명령을 가져오는 단계이다.
- **실제 분기 검증**: 실제 방향•대상을 예측과 비교해 실행 지속 또는 플러시를 결정하는 단계이다.

</details>

```text
1. 해저드 판정
├─ RAW 데이터 해저드
│  └─ 2. 결과 준비 판정
│     ├─ 준비: 포워딩
│     └─ 미준비: 스톨
└─ 분기 제어 해저드
   └─ 3. 예측 경로 인출
      └─ 4. 실제 분기 검증
         ├─ 적중: 실행 지속
         └─ 오예측: 플러시·PC·예측기 갱신
```

### 동작 원리

1. **해저드 판정**: 레지스터 의존 또는 미확정 분기 여부를 식별한다.
2. **결과 준비 판정**: 선행 결과를 우회할 수 없으면 **Load-Use 스톨**을 적용한다.
3. **예측 경로 인출**: 분기 이력과 BTB로 다음 명령 주소를 선택한다.
4. **실제 분기 검증**: 방향•대상을 대조해 실행 지속 또는 플러시와 **BTB 갱신**을 결정한다.

#### 한줄 요약
- 데이터 해저드는 우회 경로가, 제어 해저드는 예측기와 복구 로직이 각각 처리한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **적재-사용 의존**: 메모리 읽기 명령(Load) 직후 후속 명령이 해당 리소스를 참조하여 포워딩으로도 1사이클 지연이 남는 데이터 의존성이다.
- **분기 이력 기반 선인출**: 과거 방향 정보를 바탕으로 분기 결과 확정 전에 예상 경로의 명령을 가져오는 방식이다.
- **파이프라인 플러시**: 오예측한 경로에서 이미 인출/해석된 명령어를 파이프라인에서 무효화하고 제거하는 복구 동작이다.

</details>

| 해저드 대응 기법 | 포워딩 | 분기 예측 |
|:---|:---|:---|
| 적용 기준 | 기록 전 **RAW 데이터 해저드**가 발생할 때 | 분기 방향•대상 확정 전에 인출해야 할 때 |
| 핵심 특징 | 확정 결과를 레지스터 기록 전 실행 입력에 전달 | **분기 이력 기반 선인출** |
| 한계 | **적재-사용 의존**의 잔여 정체 | 오예측 시 **파이프라인 플러시** |

> 요약: 값 전달과 경로 추정을 구분해 적용한다.

#### 한줄 요약
- 포워딩은 준비된 값을 바로 전달하고 분기 예측은 다음 실행 경로를 미리 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **커밋**: 명령 실행 결과를 되돌릴 수 없는 아키텍처 상태로 최종 반영하는 단계이다.
- **정밀 예외**: 예외 명령 이전 결과만 커밋하고 이후 명령의 효과는 제거하여 정확한 상태를 복원하는 성질이다.
- **명령어 재배치**: 데이터 의존성이 없는 명령을 적재 대기 구간에 위치시켜 버블을 은닉하는 컴파일러/하드웨어 기법이다.
- **플러시 복구**: 잘못 실행한 명령을 제거하고 올바른 PC와 아키텍처 상태로 되돌리는 절차이다.
- **하드웨어 오버헤드 분석**: 제어 회로 추가로 얻는 CPI 이득과 가중되는 면적•전력 소비를 종합 평가하는 과정이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 포워딩할 적재값이 없어 **Load-Use 스톨** 발생 | **명령어 재배치**•**포워딩 장치** 검증 | 대기 주기 은닉 |
| 특정 분기에서 **분기 오예측** 반복 | 이력 길이와 **분기 대상 버퍼** 조정 | 오경로 인출•평균 CPI 감소 |
| 오예측 명령이 아키텍처 상태에 반영될 위험 | **커밋**•**플러시 복구**•**정밀 예외** 검증 | 오경로 결과 제거 |
| 포워딩•예측 회로로 면적•전력 증가 | CPI 감소량과 **하드웨어 오버헤드 분석** 비교 | 비용 대비 이득 평가 |

#### 한줄 요약
- 포워딩 적중•잔여 정체와 분기 예측 정확도•오예측 페널티를 각각 측정해야 두 기법의 CPI 개선 효과를 판단할 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **오예측 페널티**: 잘못 인출한 명령을 폐기하고 올바른 경로를 다시 채우는 동안 잃는 클록 수이다.
- **면적•전력 비용**: 포워딩•예측 회로 추가로 늘어나는 칩 공간과 에너지 소비이다.
- **해저드 제어 기준**: RAW 대기와 분기 대기의 원인 및 CPI 절감 대비 회로 비용으로 기법을 고르는 기준이다.

</details>

- **해저드 제어 기준**에 따라 RAW 대기는 **포워딩**, 분기 대기는 **분기 예측**•복구를 적용하고 **오예측 페널티**와 **면적•전력 비용**을 비교한다.

#### 한줄 요약
- 포워딩•예측 회로는 CPI 감소와 면적•전력 비용을 비교해 적용한다.
