## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어 결과를 레지스터 기록 전 후속 EX 단계 입력으로 직접 전달해 RAW 스톨을 줄이는 기법.
- **분기 예측(Branch Prediction)**: 실제 분기 결과가 확정되기 전에 다음 인출 주소를 추정해 파이프라인을 계속 채우는 기법.
- **파이프라인 스톨(Pipeline Stall)**: 의존성이나 자원 부족으로 파이프라인 단계 진행을 멈추고 버블을 삽입하는 제어.

</details>

- 정의/개념: 선행 연산 결과의 **직접 우회(Forwarding)** 와 분기 방향의 **사전 예측**으로 스톨을 줄이는 파이프라인 가속 기법
- 배경/필요성: 레지스터 기록과 분기 판정을 기다리는 동안 **파이프라인 버블** 발생

#### 한줄 요약
- 포워딩은 결과가 나오는 즉시 다음 명령어에 건네고, 분기 예측은 정답이 나오기 전에 가장 가능성 높은 경로를 먼저 달려 파이프라인을 채운다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 로드 결과가 MEM 완료 후 확정돼 즉시 EX 포워딩이 불가한 특수 RAW 의존성; 1사이클 스톨 불가피.
- **분기 오예측(Branch Misprediction)**: 예측한 분기 방향·목표 주소가 실제 결과와 달라 잘못 인출한 명령어를 플러시해야 하는 상황.
- **플러시 페널티(Flush Penalty)**: 오예측 명령어 제거와 정확한 경로 재인출에 소요되는 낭비 사이클 수.

</details>

- **포워딩**을 통한 ALU 결과의 즉시 우회 전달로 데이터 스톨 최소화
- **분기 예측**으로 분기 판정 전 다음 명령어 인출을 이어 제어 지연 은닉

#### 한줄 요약
- 두 기법은 기다림을 없애는 마법이 아니라, 이미 준비된 값과 맞을 가능성이 큰 경로를 먼저 활용해 기다림을 숨기는 방법이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 제어기(Forwarding Unit)**: 선행·후속 명령어의 소스·목적 레지스터 번호를 비교해 우회 경로를 선택하는 회로.
- **우회 다중화기(Bypass Multiplexer)**: 레지스터 파일 출력과 파이프라인 단계 결과 중 실제 실행 입력을 선택하는 회로.
- **분기 이력 테이블(Branch History Table, BHT)**: 과거 분기의 방향(성공/불성공) 이력으로 다음 방향을 예측하는 테이블.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 주소에 대응하는 예측 목표 주소를 캐싱하는 구조.
- **복구 로직(Recovery Logic)**: 오예측 후 잘못 인출된 명령어를 NOP으로 교체하고 PC를 실제 분기 목표로 복원하는 제어.

</details>

```text
[포워딩 서브시스템]
├─ 포워딩 제어기  (EX·MEM 단계 레지스터 번호 비교)
└─ 우회 다중화기  (EX/MEM·MEM/WB → EX 입력 선택)

[분기 예측 서브시스템]
├─ BHT  (분기 방향 이력 예측)
├─ BTB  (목표 주소 캐싱)
└─ 복구 로직  (오예측 시 플러시·PC 복원)
```

선의 의미: 가지(`├─`)는 서브시스템 내 소유 관계; 포워딩·분기 예측은 독립 서브시스템으로 동시 동작

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 제어기 | 레지스터 의존성 비교·우회 경로 선택 신호 발생 |
| 우회 다중화기 | 준비된 ALU·메모리 결과를 EX 단계 입력으로 선택 |
| BHT | 과거 **분기 결과 이력** 기반 방향 예측 |
| BTB | 이전 분기 목표 주소 캐싱으로 즉시 PC 제공 |
| 복구 로직 | 예측 불일치 시 잘못된 명령어 제거·**PC 복원** |

#### 한줄 요약
- 포워딩 회로는 값을 어느 단계에서 가져올지 정하고, 예측 회로는 다음에 어느 주소 명령어를 가져올지 정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 레지스터에 쓰기 전에 후속 명령어가 그 값을 읽으려는 진성 의존성.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터.

</details>

```text
명령어 파이프라인 진행 중
         │
    ┌────┴──────────────────┐
    │                       │
RAW 의존성 감지         분기 명령어 감지
    │                       │
포워딩 가능?          BHT·BTB로 방향·주소 예측
    │                       │
 예 → 우회 다중화기로    예측 PC로 다음 명령어 인출
      결과 즉시 전달         │
 아니오 (적재-사용) →   EX 단계에서 실제 결과 비교
      1사이클 스톨           │
         │            예측 일치 → 계속 실행
         │            예측 오류 → 플러시·PC 복원
```

**동작 원리**

- **포워딩 경로 선택**: 소스·목적 레지스터가 일치하면 준비된 결과를 EX 입력으로 전달
- **적재-사용 의존 처리**: 로드 결과가 확정될 때까지 스톨한 뒤 포워딩
- **분기 예측 검증**: 실제 결과가 다르면 투기 명령어를 플러시하고 PC 복원

#### 한줄 요약
- 포워딩은 값이 나오는 즉시 전달하고, 분기 예측은 맞았는지 확인될 때까지 달려가다 틀리면 되돌아온다.

## Ⅴ. 종류 및 비교

| 성능 기법 | 데이터 포워딩 | 동적 분기 예측 |
|:---|:---|:---|
| 적용 기준 | RAW 결과가 기록 전 준비돼 스톨 회피 가능 | 분기 결과 전 다음 PC 선택이 필요한 제어 해저드 |
| 핵심 특징 | 우회 다중화기로 ALU·MEM 결과 즉시 전달 | **BHT**·**BTB**로 방향과 목표 주소 투기적 추정 |
| 한계 | **적재-사용 의존**은 스톨 1사이클 불가피 | **분기 오예측** 시 플러시 페널티 발생 |

#### 한줄 요약
- 포워딩은 데이터 준비 지연을, 동적 분기 예측은 다음 주소 결정 지연을 각각 숨기는 기법이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 스케줄링(Instruction Scheduling)**: 컴파일러가 데이터 의존성을 고려해 명령어 순서를 재배치해 스톨을 줄이는 기법.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순서 실행 결과를 프로그램 순서대로 확정해 보관하는 구조.
- **비순서 실행(Out-of-Order Execution)**: 준비된 명령어를 프로그램 순서와 다르게 먼저 실행해 의존성 대기를 숨기는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **적재-사용 의존**으로 포워딩 불가 | **명령어 스케줄링**·독립 명령 삽입 | 스톨 사이클을 유용한 실행으로 대체 |
| 잦은 **분기 오예측**으로 플러시 증가 | BHT·BTB 용량·교체 정책 조정 | 예측 정확도·하드웨어 비용 균형 |
| 깊은 파이프라인에서 오예측 복구 길이 증가 | 조기 분기 판정 회로·중요 경로 단축 | **플러시 페널티** 사이클 감소 |
| 비순서 실행의 추측 결과 조기 노출 위험 | **ROB** 기반 순서 확정·예외 처리 | 정확한 프로그램 상태 보장 |

#### 한줄 요약
- 포워딩과 예측기만 넣는 것이 아니라 프로그램 의존성·분기 비율·파이프라인 깊이에 맞춰 크기와 복구 방식을 조정해야 한다.

## Ⅶ. 결론

- 현대 파이프라인은 **포워딩**과 **분기 예측**을 병행하되, 데이터 스톨 비율과 오예측 손실을 측정해 우회 경로·예측기 복잡도를 조정

#### 한줄 요약
- 포워딩과 분기 예측은 모두 성능을 올리지만, 어떤 지연이 더 자주 생기는지 측정한 뒤 그 원인에 맞는 기법부터 선택해야 한다.
