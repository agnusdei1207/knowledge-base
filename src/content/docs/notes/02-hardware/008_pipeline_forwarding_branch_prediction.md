## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어 결과를 레지스터 기록 전에 후속 실행 입력으로 직접 보내는 기법입니다.
- **분기 예측(Branch Prediction)**: 실제 분기 결과가 확정되기 전에 다음 명령어 주소를 추정하는 기법입니다.
- **파이프라인 스톨(Pipeline Stall)**: 의존성이나 자원 부족으로 파이프라인 진행을 잠시 멈추는 제어입니다.

</details>

- 정의/개념: 데이터는 우회하고 제어 흐름은 추정하는 **파이프라인 성능 기법**
- 배경/필요성: 결과 준비 대기와 분기 판정 대기로 인한 처리량 손실 완화

#### 한줄 요약

- 포워딩은 앞 결과를 빨리 건네고, 분기 예측은 다음 길을 미리 정해 파이프라인이 멈추지 않게 돕습니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 로드 결과가 준비되기 전에 바로 다음 명령어가 그 값을 요구하는 의존성입니다.
- **분기 오예측(Branch Misprediction)**: 예측한 분기 방향 또는 목표 주소가 실제 결과와 다른 상황입니다.
- **플러시 페널티(Flush Penalty)**: 오예측 명령어를 제거하고 올바른 경로를 다시 인출하며 잃는 사이클입니다.

</details>

- 포워딩: 준비된 결과 전달로 **데이터 스톨 감소**
- 분기 예측: 판정 전 인출 진행으로 **제어 지연 은닉**
- 공통 한계: 준비 지연과 오예측의 **복구 비용**

#### 한줄 요약

- 두 기법은 기다림을 없애는 마법이 아니라, 바로 쓸 수 있는 결과와 맞을 가능성이 큰 경로를 먼저 활용하는 방법입니다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 제어기(Forwarding Unit)**: 선행과 후속 명령어의 레지스터 번호를 비교해 우회 경로를 고르는 회로입니다.
- **우회 다중화기(Bypass Multiplexer)**: 레지스터 값과 파이프라인 결과 중 실행 입력을 선택하는 회로입니다.
- **분기 이력 테이블(Branch History Table, BHT)**: 과거 분기 이력으로 방향을 예측하는 테이블입니다.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 주소에 대응하는 예측 목표 주소를 보관하는 구조입니다.
- **복구 로직(Recovery Logic)**: 오예측 뒤 잘못된 명령어를 제거하고 PC를 복원하는 제어입니다.

</details>

```text
[파이프라인 성능 제어]
├─ 포워딩 제어기
├─ 우회 다중화기
├─ BHT
├─ BTB
└─ 복구 로직
```

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 제어기 | 레지스터 의존성 비교와 우회 선택 |
| 우회 다중화기 | 준비된 결과의 실행 입력 선택 |
| BHT | 과거 이력 기반 분기 방향 예측 |
| BTB | 예측된 다음 명령어 주소 제공 |
| 복구 로직 | 오예측 경로 제거와 PC 복원 |

#### 한줄 요약

- 포워딩 회로는 값을 어느 단계에서 가져올지 정하고, 예측 회로는 다음에 어느 주소의 명령어를 가져올지 정합니다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 값을 쓰기 전에 후속 명령어가 같은 값을 읽으려는 의존성입니다.
- **프로그램 카운터(Program Counter, PC)**: 다음에 인출할 명령어의 주소를 보관하는 레지스터입니다.

</details>

```text
[1. RAW와 분기 확인]
          │
          ▼
[2. 결과·예측 정보 조회]
          │
          ▼
[3. 우회 또는 예측 인출]
          │
          ▼
[4. 실제 결과 검증·복구]
```

동작 원리:

1. RAW와 분기 확인: 피연산자 의존성과 분기 명령어 식별
2. 결과·예측 정보 조회: 준비된 결과, BHT 방향, BTB 주소 확인
3. 우회 또는 예측 인출: 값 우회 또는 예측 PC로 다음 명령어 인출
4. 실제 결과 검증·복구: 미준비 결과는 스톨, 오예측 경로는 플러시

#### 한줄 요약

- 필요한 값이 이미 나왔는지와 예상한 분기 길이 맞았는지를 계속 확인해, 맞으면 진행하고 틀리면 필요한 범위만 되돌립니다.

## Ⅴ. 종류 및 비교

| 성능 기법 | 데이터 포워딩 | 동적 분기 예측 |
|:---|:---|:---|
| 적용 기준 | RAW 결과가 기록 전 준비된 경우 | 분기 결과 전 다음 PC 선택 필요 |
| 핵심 특징 | 우회 다중화기로 결과 직접 전달 | BHT·BTB로 방향과 목표 주소 추정 |
| 한계 | 적재-사용 의존에는 스톨 필요 | 오예측 때 플러시 페널티 발생 |

#### 한줄 요약

- 포워딩은 값 전달 지연을, 동적 분기 예측은 다음 주소 결정 지연을 각각 줄이는 기법입니다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 스케줄링(Instruction Scheduling)**: 독립 명령어를 재배치해 의존성 대기 시간을 숨기는 기법입니다.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차 실행 결과를 프로그램 순서대로 확정하도록 보관하는 구조입니다.
- **비순차 실행(Out-of-Order Execution)**: 준비된 명령어를 프로그램 순서와 다르게 먼저 실행하는 방식입니다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적재-사용 의존으로 포워딩 불가 | 명령어 스케줄링과 최소 스톨 적용 | 독립 명령어로 대기 시간 활용 |
| 빈번한 오예측으로 플러시 증가 | BHT·BTB 용량과 교체 정책 조정 | 정확도와 하드웨어 비용 균형 |
| 깊은 파이프라인에서 복구 길이 증가 | 조기 분기 판정과 중요 경로 최적화 | 오예측당 손실 사이클 감소 |
| 비순차 실행의 추측 결과 노출 위험 | ROB 기반 순서 확정과 예외 처리 | 정확한 프로그램 상태 보장 |

#### 한줄 요약

- 실제 설계에서는 포워딩과 예측기만 넣지 않고, 프로그램의 의존성·분기 비율·파이프라인 깊이에 맞춰 크기와 복구 방식을 조절합니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **예측 정확도(Prediction Accuracy)**: 전체 예측 중 실제 결과와 일치한 예측의 비율입니다.

</details>

- 데이터 의존성이 주된 병목이면 **포워딩**을 우선하고, 분기 비율과 **예측 정확도**가 높은 워크로드면 분기 예측을 강화하되 플러시·전력·면적 비용으로 적용 수준 결정

#### 한줄 요약

- 포워딩과 분기 예측은 모두 성능을 올릴 수 있지만, 어떤 지연이 더 자주 생기는지 측정한 뒤 그 원인에 맞는 기법부터 선택해야 합니다.
