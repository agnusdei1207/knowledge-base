## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 선행 명령어의 연산 결과를 레지스터 파일에 기록(WB)하기 전에 후속 명령어의 실행(EX) 단계 입력으로 직접 바이패스(Bypass)하여 RAW 데이터 스톨을 방지하는 기법.
- **분기 예측(Branch Prediction)**: 파이프라인에서 분기 명령어의 실제 분기 조건 및 목표 주소가 계산되기 전에 방향(Taken/Not-Taken)을 예측하여 연속적인 명령어 인출을 지원하는 기법.
- **파이프라인 스톨(Pipeline Stall)**: 데이터 의존성 또는 자원 충돌이 발생했을 때 파이프라인 단계의 전진을 일시 정지시키고 버블(Bubble)을 삽입하는 제어 동작.

</details>

- 정의/개념: 결과를 기록 전에 전달하는 **포워딩** 및 분기 방향을 사전 예측하는 **분기 예측**을 기반으로 **파이프라인 스톨**을 줄이는 기법
- 배경/필요성: 레지스터 기록과 분기 판정을 그대로 기다리면 파이프라인에 빈 슬롯이 쌓여 중첩 실행의 이득이 사라짐

#### 한줄 요약
- 두 기법의 성격은 정반대로, 포워딩은 항상 옳고 이득만 있지만 분기 예측은 틀릴 수 있어 이득과 손실을 함께 건다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적재-사용 의존(Load-Use Dependency)**: 로드 명령어의 결과가 MEM 단계를 거쳐야 확정되므로 즉시 EX 단계 포워딩이 불가능하여 최소 1클록의 스톨이 필수적인 데이터 해저드.
- **분기 오예측(Branch Misprediction)**: 예측한 분기 방향 또는 목표 주소가 실제 실행 결과와 불일치하여 잘못 인출된 명령어 파이프라인을 비워야 하는 상태.
- **플러시 페널티(Flush Penalty)**: 분기 오예측 시 잘못 진입된 파이프라인 단계를 모두 NOP으로 무효화하고 올바른 경로에서 재인출하는 데 소요되는 손실 클록 사이클 수.

</details>

- **포워딩** 통한 ALU 결과의 즉시 우회 전달로 데이터 스톨 최소화
- **분기 예측** 기반 분기 판정 전 다음 명령어 인출을 이어 제어 지연 은닉

#### 한줄 요약
- 포워딩은 실패해도 스톨로 되돌아가면 그만이지만 예측은 실패하면 이미 한 일을 버려야 하므로, 예측기는 정확도가 일정 수준을 넘어야 비로소 이득이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 제어기(Forwarding Unit)**: EX 및 MEM 단계 파이프라인 레지스터의 목적 레지스터 번호와 현재 ID/EX 단계의 소스 레지스터 번호를 비교하여 우회 멀티플렉서 제어 신호를 생성하는 하드웨어 회로.
- **우회 다중화기(Bypass Multiplexer)**: 레지스터 파일에서 읽어온 원본 데이터와 EX/MEM, MEM/WB 단계에서 우회된 최신 데이터 중 올바른 피연산자를 선택하여 ALU 입력으로 전달하는 회로.
- **분기 이력 테이블(Branch History Table, BHT)**: 과거 분기 명령어의 실행 이력(Taken/Not-Taken)을 2비트 포화 카운터 등으로 기록하여 분기 방향을 동적으로 예측하는 테이블.
- **분기 대상 버퍼(Branch Target Buffer, BTB)**: 분기 명령어의 주소를 태그로 사용하여 과거에 계산된 분기 목표 주소를 캐싱하고 IF 단계에서 즉시 다음 PC로 제공하는 구조.
- **복구 로직(Recovery Logic)**: 분기 오예측이 확정되었을 때 파이프라인 플러시 신호를 발생시키고 PC를 올바른 분기 목표 주소로 복원하는 제어 회로.

</details>

```text
[포워딩 서브시스템]
├─ 포워딩 제어기  (EX·MEM 단계 레지스터 번호 비교)
└─ 우회 다중화기  (EX/MEM·MEM/WB → EX 입력 선택)

[분기 예측 서브시스템]
├─ BHT  (분기 방향 이력 예측)
├─ BTB  (목표 주소 캐싱)
└─ 복구 로직  (오예측 시 플러시·PC 복원)
```

선의 의미: 가지(`├─`)는 서브시스템 내 소유 관계; 포워딩·분기 예측은 독립 서브시스템으로 동시 동작

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 제어기 | 레지스터 의존성 비교·우회 경로 선택 신호 발생 |
| 우회 다중화기 | 준비된 ALU·메모리 결과를 EX 단계 입력으로 선택 |
| **BHT** | 과거 분기 방향 이력을 근거로 다음 방향 예측 |
| BTB | 이전 분기 목표 주소 캐싱으로 즉시 PC 제공 |
| **복구 로직** | 예측 불일치 시 잘못된 명령어 제거와 PC 복원 |

#### 한줄 요약
- 두 서브시스템이 분리된 이유는 동작 시점이 달라서이며, 포워딩은 EX 단계에서 끝나지만 예측은 인출부터 판정까지 파이프라인 전체에 걸쳐 있다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **읽기 후 쓰기(Read After Write, RAW)**: 선행 명령어가 목적 레지스터를 갱신하기 전에 후속 명령어가 해당 레지스터 값을 참조하려 할 때 발생하는 진성 데이터 의존성.
- **프로그램 카운터(Program Counter, PC)**: 다음에 메모리에서 인출할 명령어의 주소를 저장하고 매 사이클마다 순차 증가 또는 분기 목표 주소로 갱신되는 특수 레지스터.

</details>

```text
명령어 파이프라인 진행 중
         │
    ┌────┴──────────────────┐
    │                       │
RAW 의존성 감지         분기 명령어 감지
    │                       │
포워딩 가능?          BHT·BTB로 방향·주소 예측
    │                       │
 예 → 우회 다중화기로    예측 PC로 다음 명령어 인출
      결과 즉시 전달         │
 아니오 (적재-사용) →   EX 단계에서 실제 결과 비교
      1사이클 스톨           │
         │            예측 일치 → 계속 실행
         │            예측 오류 → 플러시·PC 복원
```

분기 결과: 데이터 쪽은 값의 준비 시점만 확인하면 판정이 끝나지만, 분기 쪽은 예측한 뒤 실제 결과가 나올 때까지 판정이 유보되어 그사이 실행한 일이 모두 잠정 상태로 남음

#### 한줄 요약
- 예측이 만들어 내는 잠정 상태 구간이 곧 투기 실행의 본질이며, 성능 이득과 사이드채널 위험이 동시에 이 구간에서 나온다.

## Ⅴ. 종류 및 비교

| 성능 기법 | 데이터 포워딩 | 동적 분기 예측 |
|:---|:---|:---|
| 적용 기준 | RAW 결과가 기록 전 준비돼 스톨 회피 가능 | 분기 결과 전 다음 PC 선택이 필요한 제어 해저드 |
| 핵심 특징 | 우회 다중화기로 ALU·MEM 결과 즉시 전달 | **BHT**·**BTB** 기반 방향과 목표 주소 투기적 추정 |
| 한계 | **적재-사용 의존** 스톨 1사이클 불가피 | **분기 오예측** 시 플러시 페널티 발생 |

#### 한줄 요약
- 포워딩은 회로를 넣으면 효과가 확정되지만 예측은 워크로드의 분기 규칙성에 따라 효과가 달라지므로, 후자는 측정 없이 도입 여부를 정할 수 없다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 스케줄링(Instruction Scheduling)**: 컴파일러가 데이터 의존성 관계를 분석하여 로드-사용 의존성 등으로 인한 스톨 구간에 독립적인 명령어를 재배치하는 최적화 기법.
- **재주문 버퍼(Reorder Buffer, ROB)**: 비순차적으로 실행 완료된 명령어들의 결과를 프로그램 순서(In-Order)대로 커밋(Commit)하여 정확한 예외 처리와 프로세서 상태를 보장하는 원형 큐 구조.
- **비순서 실행(Out-of-Order Execution)**: 명령어 간의 데이터 의존성이 해소되는 즉시 프로그램 원래 순서와 관계없이 실행 유닛에 투입하여 파이프라인 유휴 시간을 제거하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **적재-사용 의존** 기반 포워딩 불가 | **명령어 스케줄링**·독립 명령 삽입 | 스톨 사이클을 유용한 실행으로 대체 |
| 잦은 **분기 오예측** 기반 플러시 증가 | BHT·BTB 용량·교체 정책 조정 | 예측 정확도·하드웨어 비용 균형 |
| 깊은 파이프라인에서 오예측 복구 길이 증가 | 조기 분기 판정 회로·중요 경로 단축 | **플러시 페널티** 사이클 감소 |
| 비순서 실행의 추측 결과 조기 노출 위험 | **ROB** 기반 순서 확정·예외 처리 | 정확한 프로그램 상태 보장 |

#### 한줄 요약
- 예측기 용량을 늘리는 대책은 수확이 빠르게 줄어드는 반면 조기 분기 판정은 깊은 파이프라인일수록 효과가 커지므로, 깊이가 대책의 우선순위를 뒤집는다.

## Ⅶ. 결론

- 현대 파이프라인은 **포워딩** 및 **분기 예측**을 병행하되, 데이터 스톨 비율과 오예측 손실을 측정해 우회 경로·예측기 복잡도를 조정

#### 한줄 요약
- 포워딩은 넣지 않을 이유가 없는 기본 설비이고 예측기는 깊이와 워크로드에 따라 규모를 정하는 선택 설비라, 둘을 같은 저울에 올리면 안 된다.
