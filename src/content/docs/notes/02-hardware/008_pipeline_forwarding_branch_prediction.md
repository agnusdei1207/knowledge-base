## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포워딩(Forwarding)**: 연산 결과를 레지스터에 쓰기 전 후속 명령어의 입력으로 직접 전달하여 데이터 대기 사이클을 제거하는 기법이다.
- **분기 예측(Branch Prediction)**: 조건 분기의 방향과 목표 주소를 사전에 추정하는 기술이다.
- **파이프라인 스톨(Pipeline Stall)**: 의존성으로 인해 명령어를 진행하지 못하고 유휴 상태로 대기하는 클록 주기이다.
- **명령어당 사이클 수(Cycles Per Instruction, CPI)**: 명령어 하나를 실행 완료하는 데 소요되는 평균 클록 주기이다.

</details>

- 정의: 데이터 의존성과 분기 지연을 해결하기 위해 연산 결과 우회 전송과 인출 경로 사전 추정을 결합한 파이프라인 최적화 기법
- 배경: 파이프라인 단계 심화로 인해 증가하는 해저드 지연을 은닉하고 **명령어당 사이클 수**를 극대화하기 위함

#### 한줄 요약

- 포워딩과 분기 예측을 통해 파이프라인 대기를 최소화하고 이상적 성능에 수렴하도록 제어하는 최적화 구조이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **분기 오예측(Branch Misprediction)**: 추정된 분기 방향이 실제 계산 결과와 일치하지 않는 오류 상태이다.
- **플러시 패널티(Flush Penalty)**: 오예측 시 오경로 명령어를 파기하고 올바른 주소에서 재인출할 때 발생하는 성능 손실이다.

</details>

- **포워딩** 기법을 통해 이전 단계 연산 결과를 후속 명령어의 연산기 입력으로 즉시 우회 전송함.
- **분기 예측** 기법을 통해 분기 타깃을 사전에 추정하여 명령어 인출 단절을 방지함.
- **분기 오예측** 발생 시 파이프라인 깊이에 비례하여 막대한 **플러시 패널티** 손실이 증가함.

#### 한줄 요약

- 데이터 우회와 분기 타깃 사전 추정으로 파이프라인 대기를 줄이지만, 예측 실패 시 페널티 손실을 수반한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **포워딩 제어기(Forwarding Unit)**: 레지스터 번호를 비교하여 우회 전송 필요성을 감지하는 제어 회로이다.
- **우회 다중화기(Bypass Multiplexer)**: 레지스터 출력값과 우회값 중 유효 피연산자를 선택하는 장치이다.
- **분기 예측기(Branch Predictor)**: 과거 이력 테이블을 기반으로 분기 방향 및 주소를 예측하는 모듈이다.
- **복구 로직(Recovery Logic)**: 오예측 시 파이프라인을 비우고 프로그램 카운터를 복구하는 회로이다.

</details>

```text
[ 데이터 및 제어 경로 최적화 구조 ]
 ├─ 데이터 해저드 경로
 │  ├─ 파이프라인 레지스터
 │  ├─ 포워딩 제어기
 │  └─ 우회 다중화기
 └─ 제어 해저드 경로
    ├─ 분기 예측기
    ├─ 인출 제어기
    └─ 복구 로직
```

| 구성요소 | 책임 |
|:---|:---|
| 포워딩 제어기 | 레지스터 비교로 우회 신호 생성 |
| 우회 다중화기 | 레지스터 값과 우회 값 중 연산기 입력 선택 |
| 분기 예측기 | 예측 테이블 기반 방향 및 타깃 주소 산출 |
| 복구 로직 | 오예측 시 파기 및 복구 제어 수행 |

#### 한줄 요약

- 포워딩 제어기와 우회 다중화기로 데이터를 전송하며, 분기 예측기와 복구 로직으로 제어 경로를 통제한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분기 이력 표(Branch History Table)**: 조건 분기의 과거 성공 및 실패 이력을 저장하는 카운터 기반 테이블이다.
- **분기 타깃 버퍼(Branch Target Buffer)**: 명령어 주소와 타깃 주소를 매핑 보관하는 캐시 메모리이다.
- **적재-사용 스톨(Load-Use Stall)**: 메모리 읽기 데이터가 확정되기 전 포워딩이 불가능해 발생하는 강제 대기 상태이다.

</details>

```text
[ 명령어 해독 및 의존성 평가 ]
        │
        ├─ 데이터 해저드 ──> [ 포워딩 다중화기 제어 ]
        │                    └─ 적재-사용 지연 시 주기 대기 후 포워딩
        │
        └─ 제어 해저드 ───> [ 동적 분기 예측기 가동 ]
                             ├─ 예측 성공 : 정지 없는 연속 인출
                             └─ 예측 실패 : 조건 연산 단계에서 파기 후 주소 복구
```

### 동작 원리

1. 의존성 검출: 해독 단계에서 레지스터 의존성 및 조건 분기를 감지함.
2. 완화 로직 적용: 우회 전송이 가능하면 포워딩을 수행하고 **적재-사용 스톨** 시 주기 대기를 주입함.
3. 분기 예측 처리: 분기 예측기를 가동하여 추정 주소로 명령어를 계속 인출함.
4. 상태 복구: 실제 연산 결과가 예측과 다를 경우 **복구 로직**이 파이프라인을 비우고 올바른 주소로 복구함.

#### 한줄 요약

- 데이터 의존에 포워딩을 적용하고 조건 분기에 예측을 적용하며 오예측 시 파기 및 복구를 집행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **쓰기 후 읽기 데이터 해저드(Read After Write Data Hazard)**: 앞 명령의 쓰기 전에 뒤 명령이 읽기를 시도하는 상태이다.
- **제어 해저드(Control Hazard)**: 조건 분기 명령어 결과가 미확정되어 인출 경로를 결정하지 못하는 상태이다.

</details>

| 비교 항목 | 포워딩 메커니즘 | 분기 예측 메커니즘 |
|:---|:---|:---|
| 대상 해저드 | **쓰기 후 읽기 데이터 해저드** 완화 | **제어 해저드** 완화 |
| 작동 방식 | 결과를 연산기 입력으로 우회 전송 | 분기 방향 및 타깃 주소를 사전 인출 |
| 제약 사항 | **적재-사용 스톨** 발생 시 대기 불가피 | 오예측 시 **플러시 패널티** 손실 부과 |
| 핵심 요소 | 제어기 및 다중화기 경로 | 분기 이력 표 및 복구 회로 |

#### 한줄 요약

- 포워딩은 데이터 우회로 연산 대기를 제거하고, 분기 예측은 선제 인출로 지연을 제거하는 체계이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령어 재배치(Instruction Reordering)**: 컴파일러가 유효한 독립 명령어를 사이에 끼워 스톨을 은닉하는 기법이다.
- **재주문 버퍼(Reorder Buffer)**: 비순차 실행 결과를 순서대로 확정하여 정밀한 상태를 보장하는 버퍼이다.
- **적재-사용 의존성(Load-Use Data Hazard)**: 적재 명령어 완료 전까지 우회가 불가능해 구조적으로 발생하는 지연 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **적재-사용 의존성** 발생에 따른 지연 | 컴파일러 기반 **명령어 재배치** 적용 | 하드웨어 대기 시간을 은닉하여 성능 유지 |
| 잦은 오예측으로 인한 파기 손실 누적 | 대규모 고급 분기 예측기 도입 및 용량 확장 | 타깃 예측 정확도 대폭 향상 |
| 오예측 경로 명령어 실행에 따른 레지스터 상태 오염 | **재주문 버퍼** 적용을 통한 상태 반영 제어 | 안전하고 정밀한 하드웨어 상태 보존 |

#### 단답형 요약

- 명령어 재배치, 고급 예측기, 재주문 버퍼를 연계하여 성능과 안전성을 모두 최적화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **해저드 제어 체계(Hazard Control Framework)**: 포워딩과 예측기를 유기적으로 통합하여 손실을 방어하는 아키텍처이다.

</details>

- 지연 분석에 기반하여 데이터 대기 병목에는 **포워딩**과 **명령어 재배치**, 분기 손실에는 **분기 예측**을 우선 적용함

#### 한줄 요약

- 해저드별 페널티를 측정하여 최적의 우회 경로와 추정 자원을 체계적으로 배분해야 한다.
