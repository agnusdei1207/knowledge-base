## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 서비스 거부(Model Denial of Service, Model DoS)**: 고비용 모델 작업을 반복해 정상 요청의 가용성을 훼손하는 자원 고갈 공격이다.
- **자원 고갈**: 토큰•GPU 시간•메모리•도구 호출을 과도하게 소비해 정상 작업을 처리하지 못하는 상태이다.

</details>

- 정의: 고비용 작업을 반복해 가용성을 훼손하는 **Model DoS**
- 배경/필요성: 전통적인 웹 서비스와 달리 거대 언어 모델(LLM) 및 생성형 AI 추론은 입력 문맥 길이(Context Window), 출력 생성 토큰 수, 멀티스텝 에이전트 도구 호출에 따라 단 한 건의 요청에도 수천 배 이상의 GPU 연산량, KV 캐시 메모리, 외부 API 비용이 소모되므로, 기존의 단순한 HTTP 요청 건수 기반 Rate Limiting(RPM) 방식만으로는 긴 컨텍스트 주입(Sponge Examples), 무한 루프 에이전트 호출, 장문 생성 유도 공격에 의해 순식간에 GPU 가용 메모리가 고갈되고 서비스 전체가 마비되는 모델 서비스 거부(Model Denial of Service: Model DoS / OWASP LLM10: Unbounded Consumption) 취약점에 직면함에 따라, 요청당/테넌트당 토큰 사용량과 실행 시간을 정밀 계량하고 멀티 테넌트 자원 격리를 수행하는 모델 DoS 방어(Model DoS Defense / Multi-dimensional Rate Limiting: TPM, RPM, Concurrent Request Caps, Dynamic KV Cache Eviction, Agent Step Budgets) 아키텍처를 도입하여 **입력/출력 토큰 및 GPU 실행 시간의 실시간 회계(Resource Accounting)를 통한 자원 독점 원천 차단, 테넌트별 독립 실행 풀(Execution Pool) 격리 및 공정 스케줄링(Fair Scheduling)을 통한 정상 요청 가용성(High Availability) 보장, 비정상적 재귀 호출 및 비용 폭증 시 즉각적인 회로 차단(Circuit Breaker) 확립**을 달성할 필요

#### 한줄 요약

- 고비용 추론 반복으로 **GPU 자원•정상 요청** 고갈

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **그래픽 처리장치 자원(Graphics Processing Unit Resource, GPU 자원)**: 모델의 행렬 연산과 캐시를 처리하는 가속기 계산•메모리 용량이다.
- **대기열 지연**: 고비용 작업이 실행 슬롯을 점유해 정상 요청의 대기 시간이 늘어나는 현상이다.
- **실행 풀 격리**: 테넌트나 작업 등급별로 처리 용량을 나눠 한 주체의 자원 독점을 제한하는 통제이다.

</details>

- 긴 입력•출력•반복에 따른 **GPU 계산•메모리 소모**
- 자원 고갈에 따른 **대기열 지연•오류•가용성 저하**
- 자원 독점을 제한하는 **주체별 예산•실행 풀 격리**

#### 한줄 요약

- 요청 수보다 **토큰•시간•도구 비용** 기반 자원 점유

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **작업량 계량기**: 요청의 입력•출력 토큰, 실행 시간과 도구 호출 사용량을 누적하는 구성요소이다.
- **스케줄러**: 테넌트별 용량과 우선순위에 따라 요청의 실행 순서와 슬롯을 배정하는 구성요소이다.
- **도구 실행기**: 외부 도구의 권한•호출 횟수•시간을 제한하며 모델 계획을 실행하는 구성요소이다.

</details>

```text
[Model DoS Defense System]
├── [인입 및 계량 계층]
│   ├── [요청 게이트웨이 (Request Gateway)]
│   └── [작업량 계량기 (Resource Meter)]
├── [스케줄링 및 큐 계층]
│   └── [대기열·스케줄러 (Queue & Scheduler)]
└── [실행 및 격리 계층]
    ├── [추론 실행기 (Inference Executor)]
    └── [도구 실행기 (Tool Runner)]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 요청 게이트웨이 | **주체 식별•한도** 적용 |
| 작업량 계량기 | **토큰•시간•도구 호출** 누적 |
| 대기열•스케줄러 | 테넌트별 **실행 풀 격리** |
| 추론 실행기 | **모델 연산•캐시** 처리 |
| 도구 실행기 | **도구 권한•시간** 제한 |

#### 한줄 요약

- 주체별 계량과 **실행 풀 격리•예산 초과 중단** 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분당 요청 수(Requests Per Minute, RPM)**: 사용자나 키별로 1분 동안 허용하는 요청 건수 한도이다.
- **분당 토큰 수(Tokens Per Minute, TPM)**: 사용자나 키별로 1분 동안 허용하는 입력•출력 토큰 수 한도이다.
- **실행 예산**: 요청 하나가 사용할 수 있는 토큰•시간•도구 호출•동시성의 상한이다.

</details>

```text
공격자
   │ 1. 고비용 요청 반복 제출
   ▼
요청 게이트웨이
   │ 2. 분산 계정•동시성 한도 우회
   ▼
대기열•스케줄러
   │ 3. 실행 슬롯•KV 캐시 점유
   ▼
추론•도구 실행기
   │ 4. 긴 생성•도구 연쇄 실행
   └── 5. 자원 고갈•서비스 지연 유발 ──▶ 정상 요청
```

### 동작 원리

1. 고비용 요청 반복 제출: 긴 입출력•재귀 계획 **작업 생성**
2. 분산 계정•동시성 한도 우회: 요청의 **다중 주체 분산**
3. 실행 슬롯•KV 캐시 점유: 추론 **계산•메모리 확보**
4. 긴 생성•도구 연쇄 실행: **GPU 시간•외부 호출 비용** 소모
5. 자원 고갈•서비스 지연 유발: 정상 요청의 **대기•오류•거부** 발생

#### 한줄 요약

- 고비용 요청의 자원 점유로 인한 **정상 요청 지연** 유발

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **입력 길이 증폭**: 긴 문맥으로 입력 연산과 KV 캐시를 과도하게 점유하는 공격 경로이다.
- **출력 길이 증폭**: 장시간 순차 생성을 유도해 생성 슬롯과 GPU 시간을 점유하는 공격 경로이다.
- **도구•에이전트 반복**: 재귀 계획과 연쇄 도구 호출로 모델 및 외부 서비스 비용을 소모하는 공격 경로이다.
- **키-값(Key-Value, KV) 캐시**: 이전 토큰의 주의 연산 키와 값을 저장해 후속 생성을 가속하는 메모리이다.

</details>

Model DoS는 입력의 KV 캐시, 출력 생성 시간, 도구 반복 비용을 각각 고갈시킨다.

| 모델 DoS 자원 소모 경로 | 입력 길이 증폭 | 출력 길이 증폭 | 도구•에이전트 반복 |
|:---|:---|:---|:---|
| 적용 기준 | 긴 문맥의 **처리 고갈** | 장시간 **순차 생성 고갈** | 재귀•**연쇄 실행 고갈** |
| 핵심 특징 | 입력 연산•**캐시 소모** | 생성 슬롯•**시간 소모** | 모델•도구의 **반복 호출** |
| 한계 | 입력 상한으로 **출력 미통제** | 출력 상한으로 **입력 미통제** | 외부 서비스로 **피해 전파** |

#### 한줄 요약

- 입력•출력•도구 반복별 **독립 실행 예산** 필요

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **긴 토큰 점유**: 적은 요청이 매우 긴 입출력을 사용해 건수 제한만으로는 자원 독점을 막지 못하는 문제이다.
- **무한 반복**: 에이전트와 도구가 종료 조건 없이 재귀 호출해 비용을 계속 소모하는 문제이다.
- **대기열 독점**: 고비용 요청이 공유 실행 슬롯을 차지해 정상 요청의 처리를 지연시키는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 적은 요청의 **긴 토큰 점유** | 사용자별 **RPM•TPM 동시 제한** | 입력•출력의 **자원 독점 차단** |
| 에이전트•도구의 **무한 반복** | 단계•시간•**도구 호출 예산** 설정 | 연쇄 **비용 고갈 방지** |
| 고비용 요청의 **대기열 독점** | 테넌트별 **실행 풀•동시성** 격리 | 정상 요청의 **가용성 보존** |

#### 한줄 요약

- 주체별 **RPM•TPM•도구 호출•동시성** 한도 적용

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **주체별 계량**: 사용자•키•조직•테넌트 단위로 자원 소비를 합산해 제한하는 방식이다.
- **예산 초과 중단**: 실행 중 누적 사용량이 상한을 넘으면 모델 생성과 도구 호출을 취소하는 통제이다.

</details>

- 생성형 AI의 막대한 고비용 GPU 컴퓨팅 인프라를 악의적 자원 고갈 및 금융 비용 폭탄 공격(Denial of Wallet)으로부터 방어하는 **엔터프라이즈 MLOps 및 클라우드 AI 서비스 가용성 보장의 최고 핵심 인프라 보안 표준(Model Denial of Service / Unbounded Token & KV Cache Consumption / Multi-dimensional Rate Limiting: RPM & TPM / Tenant Execution Pool Sandboxing & Fair Queueing / Agentic Circuit Breakers & Timeout Limits)의 확고한 표준**으로 확고히 자리 잡았으며, 대규모 서빙 엔진(vLLM, TensorRT-LLM)의 페이징 KV 캐시(PagedAttention) 및 프리엠션(Preemption) 기법과 통합되는 가운데, 실무 AI 게이트웨이 구축 시에는 **사용자/API 키별로 분당 요청 수(RPM)와 분당 토큰 수(TPM)를 동시 강제하고, 에이전트 도구 호출에 최대 반복 횟수(Max Steps)와 타임아웃 예산을 설정하며, GPU 메모리 포화 시 저우선순위 요청을 자동 축출/큐잉하는 지능형 스케줄러**를 결합하여 완벽한 서비스 연속성과 클라우드 비용 통제력을 완성

#### 한줄 요약

- 자원별 계량과 **실행 풀 격리** 기반 정상 요청 가용성 보존
