## 미리 알고가기

- **Model DoS(모델 서비스 거부 공격)**: 긴 질문을 반복해 AI가 답을 만드는 비용을 폭증시켜 정상 사용자가 서비스를 못 쓰게 하는 공격임
- **LLM(대규모 언어 모델)**: 긴 입력·출력이나 반복 작업을 시키면 한 요청도 많은 GPU 시간과 비용을 쓸 수 있음
- **RPM과 TPM**: RPM은 분당 요청 수이고 TPM은 분당 토큰 수라서, 긴 질문 공격은 TPM 제한으로 더 잘 막음

## Ⅰ. 개요

- **정의/개념**: 고비용 추론으로 모델 자원을 고갈시키는 공격이다
- **배경/필요성**: 작업량 차이에 따른 가용성·과금 피해를 막는다

### 쉽게 이해하기 (학습용)

- 짧은 주문 한 장으로도 조리가 오래 걸리는 일을 계속 시켜 다른 손님의 주문을 밀리게 만드는 공격과 같음

## Ⅱ. 특징

- 비용 비대칭은 적은 요청으로 큰 자원을 고갈시킨다
- 입력·출력·도구 반복은 서로 다른 자원을 소모한다
- 자원 고갈과 종량 과금 증가는 동시에 발생한다
- 요청 수 제한만으로 작업량 편차를 통제할 수 없다
- 누적 예산 차단은 연쇄 고갈과 서비스 중단을 막는다

### 쉽게 이해하기 (학습용)

- 손님 수가 적어도 한 명이 긴 주문과 추가 주문을 계속 내면 조리대와 비용을 모두 독점할 수 있음

## Ⅲ. 아키텍처 및 구성요소

```text
    [게이트웨이]
          │
      [스케줄러]
          │
    [실행기] ── [도구]
          └─┬─┘
        [계량기]
```

| 설계 요소 | 설명 |
|:---|:---|
| 요청 게이트웨이 | 주체 식별과 한도 적용 |
| 작업량 계량기 | 토큰·시간·도구 호출 누적 |
| 대기열·스케줄러 | 테넌트별 실행 풀 격리 |
| 추론 실행기 | 모델 연산과 캐시 처리 |
| 도구 실행기 | 도구 권한·시간 제한 |

> 요약: 주체별 작업량을 계량하고 실행 자원을 격리한다

### 쉽게 이해하기 (학습용)

- 입구에서 손님을 구분하고 계산대가 사용량을 세며, 조리 순서를 나누고 정해진 예산을 넘으면 주방이나 외부 주문을 멈추는 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
인증
 ↓
예측
 ↓
입장
 ↓
계량
 ↓
중단
```

| 절차 | 설명 |
|:---|:---|
| 요청 인증 | 사용자·정책 식별 |
| 작업량 예측 | 요청의 최대 비용 계산 |
| 입장 판정 | 예산·용량으로 승인 결정 |
| 계량 실행 | 실행 중 사용량 누적 |
| 중단·반환 | 초과 취소·완료 결과 기록 |

> 요약: 예상·누적 작업량으로 입장과 중단을 결정한다

### 쉽게 이해하기 (학습용)

- 입장권만 세지 않고 예상 주문량을 확인해 줄을 나누며, 실제 조리 중에도 사용량을 재다가 한도를 넘으면 작업을 취소함

## Ⅴ. 종류 및 비교

| 판단 기준 | 입력 길이 증폭 | 출력 길이 증폭 | 도구·에이전트 반복 |
|:---|:---|:---|:---|
| 소비 경로 | 입력 처리 연산·키-값 캐시 | 순차 생성 시간·출력 토큰 | 모델 재호출·외부 도구 실행 |
| 고갈 지점 | 메모리와 입력 처리 슬롯 | 생성 슬롯과 과금 예산 | 작업 대기열과 외부 서비스 한도 |
| 통제 기준 | 입력 토큰·컨텍스트 상한 | 출력 토큰·실행 시간 상한 | 단계·행동·도구 호출 상한 |

> 요약: 입력·출력·도구별로 다른 자원 한도를 적용한다

### 쉽게 이해하기 (학습용)

- 긴 질문은 읽는 자원, 긴 답은 쓰는 시간, 도구 반복은 다른 시스템까지 호출하는 횟수를 소모하므로 각각 다른 한도가 필요함

## Ⅵ. 실무 사례

1. 공개 모델은 사용자별 토큰·시간 예산을 적용한다
2. 코딩 에이전트는 단계·도구 한도와 차단기를 둔다

### 쉽게 이해하기 (학습용)

- 공개 챗봇은 입력·출력 토큰과 실행 시간을 재어 한 사용자의 자원 독점을 막는다.
- 코딩 에이전트는 단계·도구 호출을 제한해 순환 실행이 외부 서비스까지 고갈시키지 않게 한다.

## Ⅶ. 결론

- 토큰·시간·도구 예산과 격리 풀로 자원을 보호한다.

### 쉽게 이해하기 (학습용)

- 사람 수만 세는 출입 통제로는 부족하므로 각 사람이 쓰는 조리 시간과 추가 주문을 함께 세고 서로 다른 작업 줄에 나눠야 함
