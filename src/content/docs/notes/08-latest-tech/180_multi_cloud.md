## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **멀티클라우드(Multi-Cloud)**: 둘 이상의 공용 클라우드 제공자에 워크로드를 목적별로 배치해 함께 사용하는 운영 전략이다.
- **제공자 집중 위험**: 지역•기능•장애•가격 정책 변화의 영향이 한 클라우드 사업자에 몰린 상태이다.

</details>

- 정의: 목적별로 워크로드를 복수 제공자에 배치•운영하는 **멀티클라우드**
- 배경/필요성: 한 제공자에 모든 워크로드를 두면 그 제공자의 **장애•가격 정책 변화**가 그대로 사업 위험이 되고 협상력도 사라지므로, 대체 실행 위치와 데이터 사본을 다른 제공자에 미리 두어 전환 가능성 자체를 확보하는 구조의 필요

#### 한줄 요약

- 여러 운송사를 쓰되 각 회사의 역할과 대체 절차를 미리 정하는 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **이식성(Portability)**: 애플리케이션•데이터•운영 절차를 다른 환경으로 옮길 수 있는 정도이다.
- **통합 거버넌스**: 서로 다른 클라우드에 공통 신원•정책•태그•관측 기준을 적용하는 운영 체계이다.

</details>

- 제공자별 강점을 활용한 **목적별 워크로드 배치**
- 독립 실패 영역과 전환 훈련 기반 **복원력**
- 공통 신원•정책•관측의 **통합 거버넌스**
#### 한줄 요약

- 공급자를 늘리는 것만으로 복구력이 생기지 않으며 데이터와 운영 절차까지 준비해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **워크로드 배치 정책**: 기능•지역•규제•복구 목표에 따라 제공자별 역할과 실행 위치를 정한 규칙이다.
- **독립 실패 영역**: 동일 장애 원인에 함께 영향받지 않도록 제공자와 운영 경계를 분리한 범위이다.
- **공통 신원**: 제공자별 계정과 권한을 공통 사용자•역할 기준으로 연결하는 계층이다.
- **거버넌스**: 제공자별 정책•태그•비용 규칙을 하나의 통제 기준으로 관리하는 개념이다.
- **클라우드 연결망**: 클라우드 사이의 애플리케이션•데이터 통신 경로를 제공하는 개념이다.
- **통합 관측**: 제공자별 지표•로그•추적을 공통 맥락으로 연결하는 개념이다.
- **복원 운영**: 장애 탐지와 데이터•트래픽 전환 및 복구 훈련을 수행하는 개념이다.

</details>

```text
                  [워크로드 배치 정책]
                           |
                      [거버넌스]
                    /      |      \
          [공통 신원] [클라우드 A] [클라우드 B]
                           \       /
                    [클라우드 연결망]
                             |
                        [통합 관측]
                             |
                        [복원 운영]
```

선의 의미: 배치•통제•연결•관측•복원 운영의 정적 관계

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 배치 정책 | **기능•지역 목표**와 규제•복구 역할 정의 |
| 공통 신원 | 제공자별 **계정•권한 기준** 통합 |
| 거버넌스 | **정책 코드•태그**와 비용 규칙 통합 |
| 클라우드 A | 지정 **워크로드•데이터 서비스** 제공 |
| 클라우드 B | **보완 기능•대체 경로**와 독립 용량 제공 |
| 클라우드 연결망 | 클라우드 간 **통신•복제 경로** 제공 |
| 통합 관측 | 제공자별 **텔레메트리 상관 분석** |
| 복원 운영 | **장애 전환•복구 훈련** 수행 |

#### 한줄 요약

- 멀티클라우드에서 실제로 비싼 구성요소는 컴퓨팅이 아니라 **데이터 이동•장애 전환 관리**이며, 신원과 비용 정책을 공통화하지 않으면 제공자 수만큼 운영 규칙이 그대로 늘어난다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **주•보조 위치**: 정상 운영과 장애 전환 때 각각 워크로드와 데이터를 맡도록 정한 클라우드 환경이다.
- **전환 훈련**: 키•DNS•데이터•용량을 실제 대체 환경으로 바꾸어 복구 가능성을 검증하는 절차이다.
- **도메인 네임 시스템(Domain Name System, DNS)**: 도메인 이름을 네트워크 주소로 변환하는 분산 체계이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 일정 기간에 달성하기로 정한 사용자 중심 서비스 품질 목표이다.

</details>

```text
[업무 목표] ── 기능•지역•복구 목표 ──▶ [워크로드 배치 정책]
                                             │ 1. 제공자 역할•책임 결정
                                             ▼
                                    [공통 신원•거버넌스]
                                             │ 2. 공통 통제 적용
                                             ▼
                                      [복수 클라우드]
                                             │ 3. 배포•복제•관측
                                             ▼
[업무 목표] ◀── 전환•비용•SLO 검증 결과 ── [연결•관측•복원 운영]
```

### 동작 원리

1. 제공자 역할•책임 결정: 워크로드•데이터의 주•보조 위치 선택
2. 공통 통제 적용: 신원•정책•태그•배포 기준 구현
3. 배포•복제•관측: 연결•동기화 후 **DNS 전환•SLO** 검증

#### 한줄 요약

- 대체 클라우드의 **시간•처리 용량**과 비용 기반 전환 훈련

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하이브리드 클라우드**: 온프레미스•사설 환경과 공용 클라우드를 연결해 운영하는 모델이다.
- **단일 클라우드**: 한 제공자의 서비스와 운영 체계를 중심으로 워크로드를 표준화한 모델이다.

</details>

| 클라우드 운영 모델 | 멀티클라우드 | 하이브리드 클라우드 | 단일 클라우드 |
|:---|:---|:---|:---|
| 적용 기준 | **제공자 분산•기능 선택** | **온프레미스 연계•규제 경계** | **단순 운영•제공자 내 복원력** |
| 핵심 특징 | **복수 공용 클라우드** 배치 | **사설•공용 환경** 연결 | **단일 제공자** 중심 표준화 |
| 한계 | **통제•기술•전송•인력 비용** | **연계 복잡성•지연** | **제공자 집중 위험** |

#### 한줄 요약

- 운영 모델은 어느 계층까지 이중으로 준비할지의 차이이므로, 대체 준비를 깊게 할수록 **장애 대비**는 좋아지고 **운영비**와 공급자 공통분모 제약은 함께 커진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 중력**: 데이터 규모가 커질수록 응용과 서비스가 데이터 위치 가까이에 모이는 성질이다.
- **복구 시점 목표(Recovery Point Objective, RPO)**: 장애 시 복구 데이터가 허용할 수 있는 최대 손실 시점이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **데이터 복제 지연•충돌** | 소유권•일관성•**RPO별 복제 설계** | 전환 시 **데이터 오류** 억제 |
| 제공자 간 **전송•중복 비용** | **데이터 중력 기반 배치•비용 한도** | 예상 밖 **운영비** 감소 |
| 문서상 **대체 용량 미작동** | 정기 장애 전환•**키•DNS•용량 훈련** | **실질적 복구 능력** 확보 |

#### 한줄 요약

- 대체 클라우드의 **데이터 시점•키 접근**과 처리 용량 반복 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실질적 복구 능력**: 장애 시 정한 시간•데이터 시점•처리 용량으로 대체 클라우드가 서비스를 이어갈 수 있는 능력이다.
- **전송 비용**: 제공자와 지역 사이에서 데이터를 이동할 때 발생하는 네트워크 사용 비용이다.

</details>

- 집중 위험이 크면 **멀티클라우드**, 단순 운영이 우선이면 **단일 클라우드** 선택

#### 한줄 요약

- **복구 편익**이 복제•전송•운영 비용보다 클 때 멀티클라우드 적용
