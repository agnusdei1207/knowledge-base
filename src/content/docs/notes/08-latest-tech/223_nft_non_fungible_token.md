## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **대체 불가능 토큰(Non-Fungible Token, NFT)**: 블록체인에서 고유 식별자별 소유 상태와 이전 이력을 기록하는 토큰이다.

</details>

- 정의/개념: 블록체인에서 고유 식별자와 소유 상태를 기록하는 **NFT**
- 배경/필요성: 중앙 서비스 자산은 외부에서 **고유성•소유 이력 검증 불가**

#### 한줄 요약

- 블록체인 장부의 고유 식별자로 토큰 소유 상태와 이전 이력을 검증한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **대체 불가능성**: 각 토큰이 고유 식별자와 속성을 가져 다른 토큰과 일대일로 동일하게 교환되지 않는 성질이다.
- **토큰 식별자(Token Identifier, Token ID)**: 스마트 계약 안에서 개별 토큰을 구별하는 고유 값이다.

</details>

- 계약 주소•Token ID 조합으로 **고유 단위 식별**
- 스마트 계약으로 **발행•승인•이전 상태** 집행
- 토큰 소유와 **저작권•원본 보존** 분리
#### 한줄 요약

- 토큰 소유 상태는 검증할 수 있지만 콘텐츠 원본•저작권•재판매 권리는 별도다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메타데이터**: 대체 불가능 토큰이 가리키는 콘텐츠 주소•창작자•속성값 등을 표현하는 구조화된 데이터다.
- **스마트 계약(Smart Contract)**: NFT의 발행•소유•승인•이전 규칙을 집행하는 프로그램이다.
- **Token ID 관리**: 컬렉션 안에서 고유 식별자의 생성과 소유 상태를 관리한다.
- **외부 저장소**: 용량이 큰 메타데이터와 미디어를 저장하고 콘텐츠 해시나 주소로 토큰과 연결한다.
- **지갑**: 개인키로 토큰의 조회•이전•승인 트랜잭션에 서명하는 사용자 도구이다.
- **토큰 소유권과 저작권**: 온체인 토큰의 통제권이 원본 저작권•이용허락을 자동으로 뜻하지 않는 구분이다.
- **행성 간 파일 시스템(InterPlanetary File System, IPFS)**: 내용 주소로 파일을 식별•배포하는 분산 파일 시스템이다.

</details>

스마트 계약이 Token ID를 관리하고 **IPFS** 등에 메타데이터와 원본을 저장한 뒤 핀 고정•복제로 가용성을 유지한다.

```mermaid
block-beta
  columns 3
  N0["스마트 계약"]
  N1["Token ID"]
  N2["메타데이터"]
  N3["외부 저장소"]
  N4["지갑"]
  N0 --- N1 --- N2
  N2 --- N3 --- N4
```

| 구성요소 | 책임 |
|:---|:---|
| 스마트 계약 | **발행•소유•전송 상태** 집행 |
| Token ID | 계약 안의 **고유 단위** 식별 |
| 메타데이터 | **토큰 속성•원본 참조** 기술 |
| 외부 저장소 | **IPFS 원본•메타데이터** 저장•복제 |
| 지갑 | **키 기반 토큰 통제권** 행사 |

#### 한줄 요약

- 토큰 식별자•메타데이터•원본 저장소•지갑 키•권리 계약을 함께 관리한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **민팅(Minting)**: 스마트 계약이 새 토큰 식별자와 최초 소유 상태를 블록체인에 생성하는 과정이다.

</details>

```mermaid
sequenceDiagram
    participant R as 권리 설계•운영 체계
  participant C as 스마트 계약
  participant M as 메타데이터
  participant W as 지갑
  R->>C: 1. 권리•이전 규칙 정의
    R->>C: 토큰 발행 요청
  C->>M: 2. Token ID•메타데이터 연결
    M-->>R: 원본 해시•보존 상태 반환
  C->>W: 3. 토큰 발행•소유 상태 기록
  W->>C: 소유 상태 이전 요청
  C->>C: 4. 이전•소각 상태 갱신
    C-->>R: 상태 갱신 결과 반환
    R-->>W: 거래•생애주기 결과 반환
```

**동작 원리**

1. **권리•이전 규칙 정의**: 이용권•양도•만료•분쟁 범위 명시
2. **Token ID•메타데이터 연결**: 내용 해시로 설명•원본 결합
3. **토큰 발행•소유 상태 기록**: 계약 주소•토큰 ID•소유자 생성
4. **이전•소각 상태 갱신**: 지갑 서명•승인 규칙 검증

#### 한줄 요약

- 권리 범위를 먼저 정하고 토큰•메타데이터•원본을 연결해 이전과 소각을 관리한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **이더리움 의견 요청 721(Ethereum Request for Comments 721, ERC-721)**: 고유 토큰의 소유•조회•이전 인터페이스를 정의한 표준이다.
- **이더리움 의견 요청 1155(Ethereum Request for Comments 1155, ERC-1155)**: 여러 토큰 유형과 수량을 한 계약에서 관리하는 표준이다.
- **데이터베이스(Database, DB)**: 구조화된 데이터를 저장•조회•관리하는 시스템이다.

</details>

| 판단 기준 | ERC-721 | ERC-1155 | 중앙 DB 자산 |
|:---|:---|:---|:---|
| 적용 기준 | **고유 수집품•증서•입장권** | **게임 품목•복합 자산** | **폐쇄형 서비스 내부 자산** |
| 핵심 특징 | **ID별 고유 토큰** | **유형•수량 통합 관리** | **운영자 DB 소유 상태** |
| 한계 | **발행 비용•원본 분리** | **계약•권한 복잡성** | **운영자 종속•이동 제한** |

> 요약: **ERC-721** 은 고유 단일 자산, **ERC-1155** 는 유형•수량 통합

#### 한줄 요약

- ERC-721은 고유 단일 자산, ERC-1155는 여러 유형과 수량을 한 계약에서 관리한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **IPFS 핀 고정**: 내용 주소로 참조한 파일을 노드가 계속 보관하도록 지정해 외부 콘텐츠의 가용성을 유지한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 토큰 소유로 **법적 권리 혼동** | **이용권 계약•양도 범위** 명시 | **저작권 오인** 방지 |
| 원본 소실로 **참조 콘텐츠 접근 불가** | **내용 해시•IPFS 핀•복제** 운영 | **원본 장기 접근성** 확보 |
| 키 사고로 **무단 이전•영구 손실** | **하드웨어 지갑•다중 승인** 적용 | **무단 이전•키 분실 위험** 감소 |

#### 한줄 요약

- 핵심 운영 위험마다 실행 가능한 대책과 검증 효과를 함께 확인한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **소유 상태**: 특정 토큰을 이전할 수 있는 블록체인 주소를 장부에 기록한 정보이며 저작권 자체를 뜻하지는 않는다.

</details>

- 고유 단일 자산은 **ERC-721**, 유형•수량 통합은 **ERC-1155** 선택

#### 한줄 요약

- 발급자•원본 가용성•권리 범위•지갑 키를 함께 검증해야 한다.
