## 미리 알고가기

- **권한인지 RAG**: 검색 시 사용자 권한을 반영해 허용 문서만 검색함
- **원칙**: 후 필터링보다 사전 필터링을 원칙으로 함
- **핵심**: IAM(사용자 접근 권한 관리)과 메타데이터 동기화 품질이 중요함

## Ⅰ. 개요

- **정의/개념**: 사용자 권한을 검색·문맥·캐시에 일관 적용
- **배경/필요성**: 검색·인용·캐시 경로의 민감 정보 노출 방지

### 쉽게 이해하기 (학습용)

- 이용자가 열람할 수 있는 범위 안에서만 자료를 검색하고 답변에 사용합니다.

## Ⅱ. 특징

- 사용자·그룹·정책을 합쳐 현재의 유효 권한을 계산한다.
- 원천 권한과 색인 메타데이터 및 캐시를 동기화한다.
- 사전 필터로 허용 범위 안에서만 검색 후보를 만든다.
- 반환 전에 권한을 재검증하고 실패하면 차단한다.

### 쉽게 이해하기 (학습용)

- 사용자 신원과 원본 권한을 확인해 허용된 자료만 검색합니다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 신원 문맥 | 사용자·서비스 식별 및 속성 기록함 |
| 원천 메타데이터 | 허용·거부 주체와 권한 버전을 보관함 |
| 권한 검색기 | 유효 권한으로 허용 공간을 구성함 |
| 권한 동기화 | 권한 변경을 색인에 반영하고 추적함 |
| 통제부 | 캐시 분리·감사·권한 기록을 관리함 |

### 쉽게 이해하기 (학습용)

- 신원·원천 권한·검색기·동기화·캐시 통제가 함께 움직입니다.

## Ⅳ. 원리 및 절차 흐름도

```text
신원검증
↓
권한계산
↓
필터검색
↓
권한재검증
↓
문맥통제
```

| 절차 | 설명 |
|:---|:---|
| 신원검증 | 요청 주체와 세션 유효성 확인함 |
| 권한계산 | 정책·규칙·권한 버전 계산함 |
| 필터검색 | 허용 범위 안에서 관련성 검색함 |
| 권한재검증 | 후보의 현재 버전 재확인·차단함 |
| 문맥통제 | 허용 후보와 권한 기록을 관리함 |

### 쉽게 이해하기 (학습용)

- 권한을 계산해 검색하고 답변 문맥에 넣기 전에 다시 확인합니다.

## Ⅴ. 종류 및 비교

| 적용 기준 | 보안 색인분리 | 사전 권한필터 | 후보 검색 후 |
|:---|:---|:---|:---|
| 권한 적용 | 영역별 격리 | 검색 전 공간제한 | 문맥 전달 전 검사 |
| 적용 환경 | 등급 격리 요구 | 메타데이터 지원 | 필터 지원 없는 곳 |
| 주요 위험 | 비용·중복 운영 | 회수율 하락 | 로그·캐시 노출 |

> 요약: 적용 시점에 따라 분리·사전·후 필터로 구분함

### 쉽게 이해하기 (학습용)

- 색인 분리와 검색 전후 필터는 격리 수준·비용·노출 위험이 다릅니다.

## Ⅵ. 실무 사례

- 프로젝트 권한으로 청크를 사전 필터링함
- 인사권한 변경 시 색인과 캐시를 무효화함

### 쉽게 이해하기 (학습용)

- 소속 권한을 적용하고 권한이 바뀌면 기존 색인과 캐시를 무효화합니다.

## Ⅶ. 결론

- 권한인지 RAG는 일관된 권한 적용과 차단 우선 처리를 해야 함

### 쉽게 이해하기 (학습용)

- 검색 필터뿐 아니라 색인·캐시·인용까지 같은 권한 상태인지 확인해야 합니다.
