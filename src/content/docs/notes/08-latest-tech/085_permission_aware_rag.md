## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **권한 인지 RAG(Permission-Aware RAG)**: 요청자 권한으로 검색 공간과 답변 근거를 제한하는 방식이다.
- **접근 제어 목록(Access Control List, ACL)**: 자원별 허용•거부 주체와 권한 목록이다.

</details>

- 정의: 사용자 권한을 색인•검색•문맥•캐시에 적용하는 **권한 인지 RAG**이다.
- 배경/필요성: 일반 RAG은 원천 ACL 미보존으로 **민감정보 노출 가능**

#### 한줄 요약
- **사용자 권한**으로 검색 공간과 답변 근거 제한

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **신원•접근 관리(Identity and Access Management, IAM)**: 신원을 확인하고 유효 권한을 계산하는 체계이다.
- **권한 버전(Permission Version)**: 원천•색인•캐시의 권한 상태 식별값이다.

</details>

- 사용자•그룹•정책을 결합한 **IAM 기반 유효 권한 계산**
- 원천 ACL•색인•캐시의 **권한 버전 동기화**
- 이중 권한 통제인 **사전 필터링•반환 전 재검증**

#### 한줄 요약
- **사전 필터링•반환 전 재검증**으로 이중 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **신원 문맥(Identity Context)**: 인증 상태와 사용자•서비스•그룹을 결합한 권한 입력이다.
- **권한 검색기(Permission-aware Retriever)**: 유효 권한 범위에서만 문서를 검색한다.
- **권한별 캐시 격리**: 권한별로 캐시 영역이나 키를 분리하는 통제이다.

</details>

```text
[신원 문맥]---[원천 ACL 저장소]
     |                 |
     |          [권한 동기화기]
     |                 |
     +----------[권한 검색기]
                       |
                [문맥•캐시 통제기]
```

선의 의미: 신원•ACL•동기화•검색•캐시 통제의 정적 결합 관계이다.

| 구성요소 | 책임 |
|:---|:---|
| 신원 문맥 | 사용자•서비스•그룹의 **요청 주체 식별** |
| 원천 ACL 저장소 | 문서별 허용•거부 주체와 **권한 버전 보관** |
| 권한 동기화기 | 원천 ACL 변경의 **색인•캐시 반영** |
| 권한 검색기 | 유효 권한 범위의 **사전 필터 검색** |
| 문맥•캐시 통제기 | 반환 전 재검증과 **권한별 캐시 격리** |

#### 한줄 요약
- **신원•ACL•동기화•권한 검색•캐시 통제** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **사전 필터링(Pre-filtering)**: 검색 전에 권한으로 문서 공간을 제한한다.
- **반환 전 재검증**: 문맥 전달 직전에 최신 원천 권한을 확인한다.

</details>

```text
요청자 ── 질의•세션 ──▶ IAM
                           │ 1. 신원•유효 권한 계산
                           ▼
                       권한 검색기
                           │ 2. 허용 공간 사전 필터 검색
                           ▼
                    문맥•캐시 통제기
                           │ 3. 후보 권한 재검증
                           ▼
                         생성기
                           │ 4. 허용 문맥 기반 답변 생성
요청자 ◀── 허용 문맥 기반 답변 ──┘
```

### 동작 원리

1. 신원•유효 권한 계산: 인증 상태와 그룹•정책으로 **현재 허용 범위**를 산출함.
2. 허용 공간 사전 필터 검색: 권한 조건을 먼저 적용한 뒤 **관련 근거**를 검색함.
3. 후보 권한 재검증: 원천과 색인의 권한 버전을 대조해 **변경 후보를 차단**함.
4. 허용 문맥 기반 답변 생성: 재검증된 근거만 문맥에 결합함.

#### 한줄 요약
- **권한 계산•사전 필터•재검증•허용 문맥 생성** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **보안 색인 분리(Security Index Segmentation)**: 권한 영역별로 독립 색인을 운영한다.
- **사후 필터링(Post-filtering)**: 검색 후 권한 없는 후보를 제거한다.

</details>

| 비교 기준 | 보안 색인 분리 | 사전 권한 필터 | 사후 권한 필터 |
|:---|:---|:---|:---|
| 적용 기준 | 보안 등급별 물리•논리 격리 | 권한 메타데이터 검색 지원 | 검색 엔진의 사전 필터 미지원 |
| 핵심 특징 | 권한 영역별 **독립 색인** | 검색 전 **허용 공간 제한** | 검색 후 **비인가 후보 제거** |
| 한계 | 색인 중복•운영 비용 | 필터 조건의 회수율 영향 | 로그•캐시 선노출 위험 |

#### 한줄 요약
- **색인 격리•검색 전•검색 후**에 따라 권한 적용 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **권한 반영 지연**: ACL 변경이 색인•캐시에 늦게 적용되는 문제이다.
- **선노출(Pre-exposure)**: 권한 검증 전에 비인가 정보가 로그•캐시에 기록되는 문제이다.
- **정책 결정 충돌**: 상속과 허용•거부 규칙이 다른 결과를 만드는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 접근 제어 목록(Access Control List, ACL) 변경의 **권한 반영 지연** | 권한 버전 비교•불일치 문서 즉시 차단 | 폐기 권한의 **잔존 노출 방지** |
| 사후 필터의 **로그•캐시 선노출** | 사전 필터 우선•권한별 캐시 키 분리 | 비인가 후보의 **처리 경로 차단** |
| 그룹 상속•거부 규칙의 **정책 결정 충돌** | 명시적 거부 우선순위•정책 결정 시험 | 유효 권한의 **결정성 확보** |

#### 한줄 요약
- **권한 버전•캐시 격리•정책 결정성** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **권한 경계(Permission Boundary)**: 원천부터 답변까지 동일 정책을 적용하는 범위이다.
- **정책 결정성(Policy Determinism)**: 같은 조건에서 항상 같은 권한 결과를 내는 성질이다.

</details>

- **ACL 최신성•사전 차단•정책 결정성**으로 색인•검색•캐시 경계 결정

#### 한줄 요약
- **원천•색인•검색•캐시•답변**에 동일 권한 정책 적용
