## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **클라우드 마이그레이션 6R**: 업무 가치와 기술 조건에 따라 애플리케이션별 유지•폐기•이전•개선•재설계•교체 전략을 선택하는 체계이다.
- **6R**: Retain•Retire•Rehost•Replatform•Refactor•Repurchase의 애플리케이션 전환 전략을 의미한다.

</details>

- 정의/개념: **클라우드 마이그레이션 6R**은 업무 가치와 기술 조건에 따라 애플리케이션별 유지•폐기•이전•개선•재설계•교체 전략을 선택하는 분류 체계임.
- 배경/필요성: 일괄 이전의 **기술 부채 유지•불필요 자산 이전•과도한 재설계 비용** 방지가 필요하음.

#### 한줄 요약

- 이사할 때 물건마다 남길지 버릴지 그대로 옮길지 고치거나 새로 살지를 정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Retain**: 규제•종속성•가치 판단에 따라 현 환경에 자산을 유지하는 전략이다.
- **Retire**: 사업 가치가 없거나 중복된 자산을 종료하는 전략로 정의된다.
- **Rehost**: 애플리케이션 구조 변경을 최소화하고 인프라를 이전하는 전략이다.
- **Replatform**: 구조는 유지하면서 일부 관리형 플랫폼 기능으로 개선하는 전략이다.
- **Refactor**: 클라우드 특성을 활용하도록 애플리케이션 구조를 재설계하는 전략을 말한다.
- **Repurchase**: 기존 애플리케이션을 상용•서비스형 제품으로 교체하는 전략로 정의된다.
- **아마존 웹 서비스(Amazon Web Services, AWS)**: 클라우드 컴퓨팅 서비스를 제공하는 플랫폼로 정의된다.

</details>

- Retain•Retire 기반 **이전 제외 판단**이 핵심임.
- Rehost•Replatform 기반 **속도와 개선 폭 조절**이 핵심임.
- Refactor•Repurchase 기반 **구조•제품 전환**이 핵심임.

> **AWS 7R**은 인프라 구성을 거의 바꾸지 않고 옮기는 Relocate를 추가한다.

#### 한줄 요약

- 각 시스템의 가치와 제약뿐 아니라 서로 연결된 순서까지 보고 이전 방식을 정한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **종속성 지도**: 애플리케이션•데이터•인터페이스 사이 연결과 전환 순서를 식별한 자료이다.
- **랜딩 존**: 클라우드 이전 대상이 사용할 계정•네트워크•신원•보안•관측 기반 환경을 의미한다.
- **자산 인벤토리**: 이전 대상의 기술•비용•소유자•수명 정보를 정리한 의사결정 기초 자료을 의미한다.
- **6R 의사결정**: 업무 가치와 기술 제약을 평가해 Rehost•Replatform•Refactor•Repurchase•Retain•Retire 전략을 선택하는 과정을 말한다.
- **이전 웨이브**: 종속성을 고려하여 함께 이전할 대상 묶음과 순서를 정하는 개념이다.
- **전환(Cutover)**: 데이터 검증 뒤 운영 트래픽을 새 환경으로 넘기는 실행 단계을 의미한다.

</details>

```text
 [자산 인벤토리]---[종속성 지도]
          \           /
          [6R 의사결정]
                 |
             [랜딩 존]
                 |
            [이전 웨이브]
                 |
              [Cutover]
```

선의 의미: 자산과 종속성 정보가 6R 전략을 결정하고, 랜딩 존을 기반으로 이전 웨이브와 Cutover를 구성한다.

| 구성요소 | 책임 |
|:---|:---|
| 자산 인벤토리 | 소유자•가치•기술•비용•수명 상태 관리 |
| 종속성 지도 | 호출•데이터•인증•운영 연결 식별 |
| 6R 의사결정 | 가치•위험•기한에 따른 전략 선택 |
| 랜딩 존 | 계정•네트워크•신원•보안•관측 준비 |
| 이전 웨이브 | 대상 그룹•전환 순서 결정 |
| Cutover | 데이터•운영 트래픽 전환 |

#### 한줄 요약

- 짐 목록과 연결 관계를 조사한 뒤 이사법을 정하고 새집의 기반을 준비해 묶음별로 옮긴다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마이그레이션 웨이브**: 종속성과 위험을 고려해 함께 이전하는 대상 묶음이다.
- **Cutover**: 데이터 동기화와 검증 뒤 실제 사용자 트래픽을 새 환경으로 전환하는 단계을 말한다.

</details>

```text
[자산 인벤토리]
      │ 1. 자산•소유자 정보
      ▼
  [종속성 지도]
      │ 2. 종속성•중단 영향
      ▼
[6R 의사결정]
      │ 3. 전략•목표 환경 결정
      ▼
   [랜딩 존]
      │ 4. 웨이브 전환 준비
      ▼
[이전 웨이브•Cutover] ── 5. 검증•롤백•자산 종료 ──▶ [자산 인벤토리]
```

### 동작 원리

1. **자산•소유자 정보**: 가치•비용•기술 상태와 책임자 확인
2. **종속성•중단 영향**: 호출•데이터 흐름과 허용 중단 분석
3. **전략•목표 환경 결정**: 대상별 6R과 성공 기준 선택
4. **웨이브 전환 준비**: 랜딩 존•동기화•순서•롤백 구성
5. **검증•롤백•자산 종료**: 수용 후 폐기 또는 복귀

#### 한줄 요약

- 옮긴 뒤 정상 작동과 복귀 방법을 확인해야 이전과 기존 시스템 종료가 완성된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **7R**: 6R에 인프라 구조를 거의 바꾸지 않는 Relocate를 추가한 분류을 말한다.
- **서비스형 소프트웨어(Software as a Service, SaaS)**: 공급자가 운영하는 소프트웨어를 서비스로 사용하는 방식로 정의된다.

</details>

| 6R 전략군 | Retain•Retire | Rehost•Replatform | Refactor•Repurchase |
|:---|:---|:---|:---|
| 적용 기준 | **유지 가치•폐기 가능성** | **빠른 이전•일부 최적화** | **차별화•제품 교체 요구** |
| 핵심 특징 | **현상 유지•시스템 종료** | **인프라 이관•관리형 플랫폼** | **구조 재설계•SaaS 교체** |
| 한계 | **기술 부채•종료 종속성** | **기존 구조 제약** 잔존 | **높은 변경 비용•업무 변화** |

#### 한줄 요약

- 가치가 없으면 폐기하고 빠르게 옮길지 일부 고칠지 새로 설계하거나 구매할지를 결정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **증분 복제**: 초기 데이터 복사 뒤 발생한 변경분만 반복 동기화해 전환 중단 시간을 줄이는 방식을 말한다.
- **구성 관리 데이터베이스(Configuration Management Database, CMDB)**: IT 자산과 구성 항목의 속성•관계를 관리하는 저장소로 정의된다.
- **복구 시점 목표(Recovery Point Objective, RPO)**: 장애 시 허용 가능한 데이터 손실 시점로 정의된다.
- **복구 시간 목표(Recovery Time Objective, RTO)**: 장애 뒤 서비스를 복구해야 하는 목표 시간로 정의된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 누락된 **종속성**으로 전환 실패 | **트래픽•CMDB•인터뷰 교차 검증** | **웨이브 장애** 감소 |
| 데이터 불일치•긴 중단 | **증분 복제•리허설•Cutover 기준** 설정 | **RPO**•**RTO** 준수 |
| 이전 후 **구환경 비용 지속** | **종료 책임자•완료 조건•폐기 일정** 지정 | **이중 운영 비용** 제거 |

#### 한줄 요약

- 3계층 시스템은 호출과 데이터 순서를 확인하고 리허설한 뒤 수용 기준을 통과해야 구환경을 끈다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **구환경 종료**: 새 환경의 수용 기준을 통과한 뒤 기존 자원•계약•운영 경로를 폐기하는 단계로 정의된다.
- **롤백**: Cutover 실패 시 트래픽과 데이터 처리를 검증된 이전 환경으로 되돌리는 절차로 정의된다.

</details>

- 가치 없음은 **Retire**, 빠른 이전은 **Rehost**•**Replatform**, 차별화는 **Refactor**•**Repurchase** 선택

#### 한줄 요약

- **종속성•전환 순서•롤백•구환경 종료**까지 포함해 전략 실행
