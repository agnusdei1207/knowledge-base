## 미리 알고가기

- **관측성(Observability)**: 외부로 드러난 신호를 이용해 시스템 내부 상태와 사용자 영향을 추론하는 능력
- **텔레메트리(Telemetry)**: 원격 시스템의 상태를 측정·전송한 메트릭·로그·트레이스·프로파일 데이터
- **메트릭(Metric)**: 시간에 따른 수치 변화, **로그(Log)**: 개별 사건 기록, **트레이스(Trace)**: 요청의 분산 호출 경로
- **서비스 수준 지표(Service Level Indicator, SLI)**: '에스엘아이'로 읽으며, 사용자가 경험한 서비스 품질 측정값
- **서비스 수준 목표(Service Level Objective, SLO)**: '에스엘오'로 읽으며, 일정 기간에 달성할 SLI 목표

## Ⅰ. 개요

- 정의/개념: 텔레메트리와 실행 맥락으로 **시스템 내부 상태·원인·사용자 영향을 추론**하는 능력
- 기존 한계: 고정 임계값 중심 모니터링만으로는 동적으로 변하는 분산 환경에서 사전에 정의하지 않은 장애의 원인과 영향 경로를 설명하기 어렵다.

### 쉽게 이해하기 (학습용)

- 정해 둔 경보만 보는 것이 아니라 요청·변경·자원 신호를 연결해 예상하지 못한 문제의 원인을 찾는 능력이다.

## Ⅱ. 특징

- 메트릭·로그·트레이스·프로파일을 **시간·요청·자원·변경 기준으로 연결**한다.
- 고카디널리티 맥락으로 **사전에 정하지 않은 질문과 가설을 검증**한다.
- 샘플링·보존 비용을 통제하고 **조치 후 SLO 회복까지 확인**한다.

### 쉽게 이해하기 (학습용)

- 여러 단서를 같은 사건 기준으로 묶어 원인을 찾고, 복구 뒤 사용자 품질이 실제로 회복됐는지 확인한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[계측] → [수집·처리] → [저장·질의]
             ↑               ↓
         [맥락 모델] → [SLO·대응]
```

| 설계 요소 | 설명 |
|:---|:---|
| 계측 | **메트릭·로그·트레이스 생성** |
| 수집 파이프라인 | **정규화·필터·샘플링·전송** |
| 맥락 모델 | **요청·자원·버전·팀 연결** |
| 저장·질의 | **신호 보존과 가설 탐색** |
| 대응 체계 | **SLO 판단·조치·회복 검증** |

> 요약: 맥락 있는 신호를 질문·가설·조치 검증으로 연결한다.

### 쉽게 이해하기 (학습용)

- 신호를 저장하는 데서 끝내지 않고 어떤 변경과 요청에서 문제가 생겼는지 탐색할 수 있어야 한다.

## Ⅳ. 원리 및 절차 흐름도

```text
신호 생성 → 맥락 부여 → 수집 통제 → 질문 형성 → 가설 검증 → 조치·확인
```

| 절차 | 설명 |
|:---|:---|
| 신호 생성 | 메트릭·로그·추적·프로파일 기록 |
| 맥락 부여 | 요청·자원·버전·팀 연결 |
| 수집 통제 | 정규화·필터·샘플링·보존 |
| 질문 형성 | 사용자 영향 중심 질문 정의 |
| 가설 검증 | 관련 신호와 변경 비교 |
| 조치·확인 | 복구 후 SLO 회복 확인 |

> 요약: 맥락 있는 신호로 가설을 검증하고 조치 결과를 사용자 지표로 확인한다.

### 쉽게 이해하기 (학습용)

- 증상과 변경·요청 경로를 대조해 조치한 뒤 같은 품질 지표의 회복을 본다.

## Ⅴ. 종류 및 비교

| 운영 상태 이해 방식 | 텔레메트리 | 모니터링 | 관측성 |
|:---|:---|:---|:---|
| 적용 기준 | 분석용 원시 신호 제공 | 알려진 조건 지속 감시 | 미지 현상 원인 탐색 |
| 핵심 특징 | 상태 신호 생성·전송 | 임계값·대시보드·경보 | 맥락 기반 가설 검증 |
| 한계 | 신호만으로 원인 추론 불가 | 미지 원인 설명 한계 | 비용·카디널리티 증가 |

> 요약: 텔레메트리는 재료, 모니터링은 알려진 조건 감시, 관측성은 미지 원인 추론이다.

### 쉽게 이해하기 (학습용)

- 측정값을 만들고, 정해진 이상을 감시하며, 예상하지 못한 문제는 맥락을 연결해 탐색한다.

## Ⅵ. 실무 사례

1. **결제 실패 트레이스와 배포 버전 연결 후 롤백**

### 쉽게 이해하기 (학습용)

- 실패 요청의 로그·트레이스·배포 정보를 묶어 결함을 찾고 회복을 확인한다.

## Ⅶ. 결론

- 분산 시스템의 내부 상태와 사용자 영향을 추론하기 위해 **로그·메트릭·트레이스·배포 문맥·SLI·수집 비용**을 검토하고, 원인 규명과 조치 후 품질 검증에 필요한 신호를 계측한다.

### 쉽게 이해하기 (학습용)

- 많이 모으는 것보다 필요한 질문에 답하고 실제 복구까지 확인하는 것이 중요하다.
