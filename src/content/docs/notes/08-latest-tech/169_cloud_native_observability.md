## 미리 알고가기

- **관측성**: 시스템 상태를 외부 신호로 추론하는 능력
- **필요성**: 서비스 동적 환경에서 신호의 결합이 필수임
- **모니터링**: 알려진 문제 감지와 관측성 탐색의 차이임



## Ⅰ. 개요

- **정의/개념**: 동적 시스템 텔레메트리의 맥락 분석
- **배경/필요성**: SLO 위반의 사용자 영향·원인 설명

### 쉽게 이해하기 (학습용)

- 관측성은 사용자 요청의 영향 구간과 원인을 신호로 찾는 능력이다.

## Ⅱ. 특징

- 메트릭·로그·트레이스·프로파일을 연결한다
- 자원·버전·팀 맥락이 사라진 자원을 설명한다
- 질문 기반 탐색이 미지의 장애 원인을 찾는다
- 조치 뒤 사용자 지표 회복을 확인한다
- 신호 가치·비용으로 수집 범위를 정한다

### 쉽게 이해하기 (학습용)

- 여러 신호를 같은 시간·요청·변경 기준으로 연결해야 원인을 설명한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[계측] → [수집·처리] → [저장·질의]
             ↑               ↓
         [맥락 모델] → [SLO·대응]
```

| 설계 요소 | 설명 |
|:---|:---|
| 계측 | 메트릭·로그·추적 생성 |
| 파이프라인 | 정규화·필터·전송 |
| 맥락 모델 | 요청·자원·변경 연결 |
| 저장·질의 | 신호 보존·탐색 |
| 대응 체계 | SLO 판단·조치·검증 |

> 요약: 신호를 맥락·질문·조치에 연결하는 피드백 구조다

### 쉽게 이해하기 (학습용)

- 신호를 쌓는 데서 끝내지 않고 사건 맥락과 대응 행동까지 연결한다.

## Ⅳ. 원리 및 절차 흐름도

```text
신호 생성 → 맥락 부여 → 질문 형성
                         ↓
회복 확인 ← 조치 실행 ← 가설 검증
```

| 절차 | 설명 |
|:---|:---|
| 신호 생성 | 메트릭·로그·추적·프로파일 기록 |
| 맥락 부여 | 요청·자원·버전·팀 연결 |
| 수집 통제 | 정규화·필터·샘플링·보존 |
| 질문 형성 | 사용자 영향 질문 정의 |
| 가설 검증 | 관련 신호·변경 비교 |
| 조치·확인 | 복구 뒤 SLO 회복 확인 |

> 요약: 맥락 있는 신호로 가설을 검증하고 회복을 확인한다

### 쉽게 이해하기 (학습용)

- 증상과 변경·요청 경로를 대조해 조치하고 같은 지표의 회복을 본다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 텔레메트리 | 모니터링 | 관측성 |
|:---|:---|:---|:---|
| 핵심 역할 | 외부 신호 제공 | 정의 조건 평가 | 내부 상태 추론 |
| 답하는 질문 | 어떤 원자료가 있는가 | 알려진 문제가 생겼는가 | 미지 현상이 왜 생겼는가 |
| 운영 결과 | 측정 데이터 | 대시보드·경보 | 가설·영향·조치 검증 |

> 요약: 신호·조건 감시·미지 탐색은 서로 다른 역할이다

### 쉽게 이해하기 (학습용)

- 텔레메트리는 재료, 모니터링은 검사, 관측성은 미지 탐색이다.

## Ⅵ. 실무 사례

1. 결제 실패 추적과 배포 버전을 연결해 롤백한다
2. 리전별 느린 추적에서 연결 풀 고갈을 찾는다

### 쉽게 이해하기 (학습용)

- 실패 요청의 로그·추적·배포를 묶어 결함을 찾고 회복을 확인한다.
- 평균 대신 영향 집단을 좁혀 지연 경로와 재시도 증폭을 찾는다.

## Ⅶ. 결론

- 사용자 질문에 필요한 신호를 연결하고 조치 결과를 검증한다.

### 쉽게 이해하기 (학습용)

- 많이 모으기보다 필요한 질문에 답하고 실제 복구까지 확인해야 한다.
