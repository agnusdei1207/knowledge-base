## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **제로 트러스트 아키텍처(Zero Trust Architecture, ZTA)**: 네트워크 위치의 암묵적 신뢰 없이 자원별 접근을 지속 검증하고 최소 권한으로 집행하는 보안 구조로 정의된다.
- **제로 트러스트**: 네트워크 위치만으로 주체나 장치를 암묵적으로 신뢰하지 않는 보안 원칙이다.

</details>

- 정의: 네트워크 위치를 신뢰하지 않고 자원별 접근을 검증하는 **ZTA**
- 배경/필요성: 경계 내부 신뢰는 침해 후 **과도한 권한•횡적 이동 차단 곤란**

#### 한줄 요약

- 자원마다 **주체•장치•업무 목적**을 다시 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최소 권한**: 업무에 필요한 자원•행위•시간만 허용하는 원칙을 말한다.
- **지속적 재평가**: 세션 중 행위•위협•장치 상태 변화를 관찰해 권한을 축소•회수하거나 재인증하는 과정을 의미한다.

</details>

- 주체•장치 상태와 민감도를 결합한 **자원 중심 검증**
- 자원•행위•시간•세션을 제한하는 **동적 최소 권한**
- 위험 변화에 따라 권한을 회수하는 **지속적 재평가**

#### 한줄 요약

- 자원별 **신원•장치•업무 목적** 검증과 세션 중 권한 회수

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 엔진(Policy Engine, PE)**: 주체•장치•자원•위험 정보를 평가해 접근 허용•거부•회수를 결정하는 기능이다.
- **정책 관리자(Policy Administrator, PA)**: 정책 결정에 따라 연결 경로와 자격증명을 생성•종료하는 기능이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: 주체와 자원 사이에서 접근 결정을 실제로 집행하는 지점이다.

</details>

```text
                 [주체•장치]
                      |
                 [정책 집행점]
                      |
                 [정책 관리자]
                      |
                  [정책 엔진]
                      |
                  [신호•자원]
```

| 구성요소 | 책임 |
|:---|:---|
| 주체•장치 | 사용자•서비스 **신원•장치 상태** 제시 |
| 정책 집행점 | 자원 연결의 허용•차단과 **세션 활동** 집행 |
| 정책 관리자 | 경로 생성•종료와 **세션 자격증명** 발급 |
| 정책 엔진 | 정책•위험 신호 기반 허용•거부와 **권한 회수** 결정 |
| 신호•자원 | 신원•자산•위협 정보와 **보호 대상** 제공 |

#### 한줄 요약

- **정책 집행•연결 제어•위험 판단**의 역할 분리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **접근 맥락**: 주체 신원•장치 상태•요청 행위•자원 민감도를 결합한 판단 정보이다.
- **세션 수명**: 승인한 연결과 자격증명이 유효하게 유지되는 시간과 종료 조건을 의미한다.

</details>

```text
[주체•장치] ── 접근 요청 ──▶ [정책 집행점]
                                  │ 1. 접근 맥락
                                  ▼
                              [정책 엔진]
                                  │ 2. 정책 결정
                                  ▼
                             [정책 관리자]
                                  │ 3. 세션 제어
                                  ▼
[주체•장치] ◀── 자원 응답 ── [자원] ◀─ 4. 허용 요청 ─ [정책 집행점]

[정책 집행점] ── 세션 신호 ──▶ [정책 엔진]
                                  │ 5. 세션 재평가 결정
                                  ▼
[정책 집행점] ◀─ 권한 축소•회수 ─ [정책 관리자]
```

### 동작 원리

1. 접근 맥락: 신원•장치•행위와 **자원 민감도** 제공
2. 정책 결정: 허용•거부•제한과 **세션 수명** 제공
3. 세션 제어: 경로•자격증명의 **생성•종료 조건** 제공
4. 허용 요청: 승인된 **자원•행위 범위** 한정 연결
5. 세션 재평가 결정: 위험 변화에 따라 **권한 유지•축소•회수** 결정

#### 한줄 요약

- **접근 맥락•정책 결정•세션 제어•재평가**의 환류

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **경계형 보안**: 내부망과 외부망의 경계 통과를 중심으로 접근을 집중 통제하는 구조이다.
- **가상 사설망(Virtual Private Network, VPN)**: 원격 사용자를 사설망에 암호화된 네트워크 경로로 연결하는 기술을 말한다.

</details>

| 구분 | 제로 트러스트 아키텍처 | 경계형 보안 | 가상 사설망 |
|:---|:---|:---|:---|
| 적용 기준 | 분산 자원의 **세밀한 접근** | 고정 **내부망 경계** 보호 | 원격 사용자의 **사설망 연결** |
| 핵심 특징 | 자원별 **동적 정책•지속 검증** | 경계 통과 전 **집중 통제** | **암호화 네트워크 경로** 제공 |
| 주요 한계 | **자산 식별•신호 품질** 관리 복잡 | 내부 침해의 **횡적 이동** 위험 | 접속 후 **자원별 최소 권한** 부족 |

#### 한줄 요약

- **자원별 검증•경계 보호•원격 연결**에 따른 보안 구조 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **횡적 이동**: 침해된 계정이나 장치를 발판으로 내부의 다른 자원에 접근하는 공격을 말한다.
- **관찰 모드**: 새 접근 정책을 바로 차단에 쓰지 않고 예상 판정과 업무 영향을 기록하는 검증 방식을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **자산•주체 식별 누락**에 따른 정책 밖 계정 | **지속 탐지•소유자•민감도•기본 거부** 적용 | 미관리 자산 **정책 우회** 차단 |
| **정책 과잉•충돌**에 따른 업무 차단•장기 예외 | **관찰 모드•정책 모의시험•단계 배포** | 업무 차단•**장기 예외** 감소 |
| **신호 신뢰성 부족**에 따른 장치•위협 정보 오판 | **출처•최신성•다중 신호•안전 정책** 검증 | **접근 오판률** 감소 |

#### 한줄 요약

- **식별•정책•신호 위험**별 접근 통제 효과 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **권한 회수**: 세션 위험이 커졌을 때 이미 허용한 자원 접근과 자격증명을 즉시 종료하는 통제로 정의된다.
- **자원 민감도**: 침해 시 업무•법률•개인정보 영향을 기준으로 분류한 보호 대상의 중요도이다.

</details>

- 자원 민감도가 높으면 **접근별 검증**, 세션 위험이 커지면 **권한 회수**

#### 한줄 요약

- **자원 민감도•세션 위험**에 따라 최소 권한 부여•회수
