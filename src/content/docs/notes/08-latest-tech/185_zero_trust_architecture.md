## 미리 알고가기

- **제로 트러스트(Zero Trust, ZT, 지티)**: 네트워크 위치만으로 암묵적 신뢰를 부여하지 않는 보안 원칙
- **ZTA(지티에이)**: Zero Trust Architecture의 머리글자로, 제로 트러스트 원칙을 구현한 자원 중심 아키텍처
- **PE·PA·PEP(피이·피에이·피이피)**: 정책 엔진이 판단하고 정책 관리자가 경로를 제어하며 정책 집행점이 접근을 집행



## Ⅰ. 개요

- 정의/개념: 위치 기반 암묵적 신뢰 없이 주체·장치·자원별 접근을 동적으로 검증하는 아키텍처다
- 기존 한계: 경계 내부 접속을 신뢰하면 계정·장치 침해 후 다른 자원으로 횡적 이동할 수 있다
- 기존 한계: 내부망을 신뢰하는 경계형 보안은 계정·단말이 침해되면 내부 자원으로의 횡적 이동과 과도한 권한 사용을 막기 어렵다.

### 쉽게 이해하기 (학습용)

- 건물 안에 들어왔어도 각 방에서 사람·기기·업무 목적을 다시 확인하는 방식과 같다.

## Ⅱ. 특징

- 네트워크 위치가 아닌 자원·주체·장치 신원을 기준으로 판단한다
- 최소 권한과 동적 정책으로 허용 자원·행위·시간을 제한한다
- 세션 중에도 위험 변화를 관찰해 접근을 재평가한다

### 쉽게 이해하기 (학습용)

- 신분증만 보지 않고 작업 목적을 확인하며 위험 시 권한을 즉시 거둠

## Ⅲ. 아키텍처 및 구성요소

```text
                   [Identity / Device / Threat / Logs]
                                  ↓
[Subject] → [PEP] ⇄ [Policy Administrator] ⇄ [Policy Engine]
               │             control plane
               └──── allowed data path ────→ [Resource]
```

| 설계 요소 | 설명 |
|:---|:---|
| 자원 식별 | 주체·서비스·장치 상세 목록화 및 민감도 연결 |
| 정책 엔진 | 정책·위협 정보 기반의 허용·거부·회수 결정 |
| 정책 관리자 | 경로 생성·종료 명령 및 자격증명 발급 |
| 정책 집행점 | 주체·자원 간 연결 감시·차단·집행 |
| 분석 계층 | 신원·장치·로그·보안 정보를 수집·제공 |

> 요약: 엔진 판단·관리자 제어·집행점 실행

### 쉽게 이해하기 (학습용)

- 심사관이 판단하고 관리자가 출입증 발급, 문 앞 장치가 개폐 수행

## Ⅳ. 원리 및 절차 흐름도

```text
접근 요청 → 신원·장치·위험 수집 → 정책 결정
                                      ↓
자원 접근 ← PEP 집행 ← PA 경로 설정 ← 허용
                                      ↘ 거부
```

| 절차 | 설명 |
|:---|:---|
| 1. 요청 식별 | 주체·장치·대상 자원을 식별함 |
| 2. 맥락 수집 | 인증·장치·행위·위협 정보를 엔진으로 전달함 |
| 3. 동적 결정 | 위험 기준 허용·거부·제한 결정함 |
| 4. 경로 설정 | 세션 경로 생성 및 자격증명 발급함 |
| 5. 집행 | 허용된 자원·행위에 한해 데이터 경로 열람함 |
| 6. 연속 재평가 | 위험 변화 관찰 후 재인증·권한 축소 수행함 |

> 요약: 로그인 이후에도 위험 변화를 관찰해 접근을 재평가한다

### 쉽게 이해하기 (학습용)

- 장치 상태나 행동이 바뀌면 접근 권한을 다시 판단한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | ZTA | 경계형 보안 | VPN |
|:---|:---|:---|:---|
| 적용 기준 | 분산 자원의 세밀한 접근 | 고정된 내부망 경계 보호 | 원격 사용자의 사설망 접속 |
| 핵심 특징 | 자원별 동적·지속 검증 | 경계 통과 후 내부 신뢰 | 암호화된 네트워크 경로 제공 |
| 한계 | 자산 식별·정책 운영 복잡 | 내부 침해의 횡적 이동 위험 | 접속 후 자원별 통제 부족 |

> 요약: 네트워크 위치 대신 자원별 요청과 위험을 평가한다

### 쉽게 이해하기 (학습용)

- 경계형 보안과 VPN은 입구를 보호하고 ZTA는 각 자원 요청을 별도로 판단한다.

## Ⅵ. 실무 사례

1. 외부 개발자는 관리 단말·강한 인증·작업 시간 검증을 통과한 뒤 허용된 운영 도구에만 접근한다.

### 쉽게 이해하기 (학습용)

- 접속 위치를 신뢰하지 않고 사용자·단말·작업 맥락을 매번 확인해 최소 권한만 부여한다.

## Ⅶ. 결론

- 분산 자원의 무단 접근을 차단하기 위해 신원·단말 상태·행위 위험을 지속 검토하여 제로 트러스트 아키텍처를 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 제로 트러스트는 단일 제품이 아니라 최소 권한과 지속 검증을 구현하는 운영 체계다.
