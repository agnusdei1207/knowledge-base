## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **에이전트 권한 제어**: 에이전트가 위임받은 범위 안에서만 자원과 도구를 사용하도록 인증•인가•승인을 강제하는 통제 체계을 말한다.
- **인증(Authentication)**: 접근을 요청하는 사용자•에이전트•도구의 신원을 확인하는 절차로 정의된다.
- **인가(Authorization)**: 인증된 주체가 특정 자원에 어떤 행동을 할 수 있는지 결정하는 절차을 의미한다.
- **최소 권한(Least Privilege)**: 업무 수행에 필요한 최소 범위와 시간으로 권한을 제한하여 부여하는 원칙을 말한다.

</details>

- 정의/개념: 위임 범위의 자원•도구 행동을 제한하는 **에이전트 권한 제어**임.
- 배경/필요성: 광범위한 고정 권한은 의도 밖 행동•권한 남용•피해 확산을 유발하므로 **인가**가 필요하음.

#### 한줄 요약
- 작업별 **최소 권한**과 승인 경계를 부여하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **권한 위임(Delegation)**: 사용자가 에이전트에게 수행할 행동의 범위와 기간을 정해 권한을 넘기는 행위이다.
- **정책 결정점(Policy Decision Point, PDP)**: 정책과 주체•자원•환경 속성을 평가하여 접근 허용 여부를 판단하는 지점을 말한다.
- **정책 집행점(Policy Enforcement Point, PEP)**: PDP의 결정을 도구 호출 직전에 허용이나 거부로 강제하는 지점이다.
- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 행동을 사람이 검토하고 승인하는 통제 방식을 말한다.

</details>

- **인증**: 사용자•에이전트•도구 신원을 확인함.
- **권한 위임**: 대리 행동의 범위•기간을 제한함.
- **PDP**: 주체•자원•환경 속성으로 허용 판단임.
- **PEP**: 정책 판단을 도구 호출 전에 강제임.
- **최소 권한**: 실행 권한과 피해 범위를 제한함.
- **HITL**: 고위험 행동을 사람의 승인으로 제한함.

#### 한줄 요약
- 열람•변경 권한을 분리하고 고위험 행동을 재확인하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **정책 관리**: 역할•속성•금지 규칙과 정책 버전을 정의하고 변경하는 기능을 의미한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 에이전트가 외부 기능을 요청하는 호출 경계로, PEP가 정책을 집행하는 지점을 의미한다.

</details>

```text
 [인증•위임]       [정책 관리]
          \             /
             [정책 결정점]
                    |
             [정책 집행점] ----- [승인•감사]
```

선의 의미: 정책 결정점은 인증•위임 정보와 정책 관리의 규칙을 결합하고, 정책 집행점은 그 판단 및 승인•감사 통제를 도구 접근 경계에 강제하는 정적 권한 제어 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 인증•위임 | 사용자•에이전트의 신원•대리 범위 확인 |
| 정책 관리 | 역할•속성•금지 규칙을 **정책 관리**로 정의 |
| 정책 결정점 | 주체•자원•환경으로 허용 여부 판단 |
| 정책 집행점 | **API** 호출 전 허용•거부 강제 |
| 승인•감사 | 고위험 행동의 **HITL** 승인•결과 기록 |

#### 한줄 요약
- 모델 제안을 **PDP•PEP•HITL** 계층이 통제한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **정책 질의**: PEP가 요청의 주체•자원•행동•환경 정보를 PDP에 전달하여 허용 여부를 묻는 과정이다.
- **추가 승인**: 정책상 고위험으로 분류된 행동을 실행하기 전에 사용자에게 최종 결정을 요청하는 절차을 말한다.
- **자원•행동•인자 요청**: 에이전트가 사용하려는 자원과 행동 및 호출 인자를 PEP에 전달하는 절차을 말한다.
- **허용•거부 결정**: PDP가 정책 질의 결과에 따라 요청의 실행 가능 여부를 판정하는 절차을 말한다.
- **승인된 API 행동 실행**: PEP가 허용 및 추가 승인을 받은 범위의 API 호출만 전달하는 절차로 정의된다.

</details>

- **PEP** 측에서 **PDP** 판단을 받아 **API** 호출 직전에 허용•거부와 추가 승인을 강제함.

```text
사용자
   │ 최소 범위•기간 위임
   ▼
에이전트
   │ 1. 자원•행동•인자 요청
   ▼
PEP
   │ 2. 주체•환경 정책 질의
   ▼
PDP
   │ 3. 허용•거부 결정
   ▼
PEP
   ├───────────────────┐
   │ 고위험 행동이면   │◄──── 사용자 추가 승인
   └─────────┬─────────┘
   │ 4. 승인된 API 행동 실행
   ▼
도구 API
   │ 실행 결과•오류 반환
   ▼
에이전트
```

1. **자원•행동•인자 요청**: PEP에 실행 의도를 전달함.
2. **주체•환경 정책 질의**: PDP가 역할•속성•상황 조건을 평가함.
3. **허용•거부 결정**: 호출 직전 **최소 권한**을 강제함.
4. **승인된 API 행동 실행**: **추가 승인**까지 받은 도구만 호출함.

#### 한줄 요약
- **PDP 판단•PEP 집행•HITL 승인** 후 도구를 실행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **역할 기반 접근통제(Role-Based Access Control, RBAC)**: 직무 역할에 권한을 묶고 사용자나 에이전트에 역할을 할당하는 방식을 말한다.
- **속성 기반 접근통제(Attribute-Based Access Control, ABAC)**: 주체•자원•행동•환경 속성을 정책으로 평가하여 접근을 결정하는 방식을 의미한다.

</details>

- **RBAC** 및 **ABAC** 사이를 안정적 직무 권한과 동적 상황 판단 기준으로 구분함.

| 접근통제 | RBAC | ABAC |
|:---|:---|:---|
| 적용 기준 | 직무별 권한이 안정적 | 상황별 동적 판단 필요 |
| 핵심 특징 | 역할에 권한 결합 | 주체•자원•환경 속성 평가 |
| 한계 | 역할 폭증•세밀성 부족 | 정책 복잡•판단 추적 부담 |

> 요약: 안정적 역할에는 **RBAC**, 동적 속성 통제에는 **ABAC**을 적용한다.

#### 한줄 요약
- **RBAC•ABAC**로 단일 도구와 조합 행동까지 통제한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **단기 자격증명**: 작업이 끝나거나 정해진 시간이 지나면 자동 만료되어 권한 잔존을 줄이는 인증 정보이다.
- **권한 상승**: 허용된 여러 도구를 조합하여 본래 위임 범위를 넘는 행동이 가능해지는 현상을 의미한다.
- **책임 추적성**: 권한을 요청•판단•승인•실행한 주체와 결과를 연결하여 사후 책임을 확인하는 성질을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장기 토큰에 따른 권한 잔존 | 작업별 **단기 자격증명**과 자동 만료 적용 | 위임 종료 후 접근 차단 |
| 도구 조합에 따른 **권한 상승** | 전체 행동 경로를 정책으로 평가 | 연쇄 호출의 우회 실행 방지 |
| 고위험 행동의 자동 실행 | 금액•대상•외부 전송별 **HITL** 요구 | 되돌리기 어려운 부작용 통제 |
| 정책 결정의 책임 공백 | **책임 추적성**을 위해 주체•정책 버전•결정•결과 연결 | 권한 사용 추적 |

#### 한줄 요약
- 송신 권한과 수신 도메인을 분리해 무단 전송을 차단하는 것이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **권한 통제 구분**: 안정적 직무 권한에는 RBAC를, 동적 속성•도구 조합•상황 판단에는 ABAC를 적용해 권한 상승을 통제하는 결정을 말한다.

</details>

- **권한 통제 구분**에 따라 안정적 직무 권한에는 **RBAC**, 동적 맥락•도구 조합에는 **ABAC**을 선택함.

#### 한줄 요약
- 작업별 **최소 권한**과 고위험 **HITL**을 적용한다.
