## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **인공지능 에이전트 시스템(AI Agent System)**: 목표(Goal)를 작업(Task)으로 계획하고 도구(Tool)를 실행하며 관찰 결과에 따라 행동을 조정하는 자율 시스템. 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소.

</details>

- 정의: 인공지능 에이전트 시스템(AI Agent System)은 명확한 목표(Goal)를 기반으로 작업(Task)을 계획, 도구(Tool)를 실행하며 관찰 결과에 따라 행동을 조정하는 자율 시스템으로, 기업의 실질적 가치 창출을 위해 제어 가능한 실행 환경을 제공함.
- 배경: 단일 생성 모델은 장기 상태 유지, 외부 도구 실행, 오류 복구 처리가 불가능하여 복잡한 실무 업무 자동화에 한계 존재.

#### 한줄 요약
- **AI Agent**는 목표 분해, 도구 실행, 재계획을 수행하는 자율적 문제 해결 체계 적용

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **목표 지향성(Goal-Oriented)**: 최종 목표를 의존 관계와 완료 조건이 있는 하위 작업으로 분해. 실무 환경의 안정성과 효율성을 보장하는 핵심 기전.
- **추론-행동(ReAct, Reasoning and Acting)**: 추론으로 행동을 선택하고 결과 관찰을 통해 오류 복구 및 재계획에 반영하는 반복 방식. 구조적 완결성과 성능을 제공하는 기술 기반.
- **계획 축(Planning Axis)**: 목표를 하위 작업으로 분해하고 의존성, 상태, 완료 조건을 관리하는 기능 영역.
- **실행 축(Execution Axis)**: 도구 실행 결과를 관찰해 오류를 복구하고 다음 행동을 재계획하는 기능 영역. 복잡한 문제 해결과 환경 적응의 핵심.
- **통제 축(Control Axis)**: 권한, 승인, 비용, 감사 정책으로 에이전트의 행동 범위를 제한하는 기능 영역. 시스템 안정성과 신뢰성 확보의 필수 기전.

</details>

- 계획 축: 최종 목표를 의존성 및 완료 조건이 명시된 하위 작업으로 분해하여 실무 업무의 구조적 안정성과 지속적 최적화 지원.
- 실행 축: ReAct(Reasoning and Acting) 기반의 반복적 추론과 오류 복구를 통해 외부 환경 변화에 적응하고 실시간 행동 조정을 수행.
- 통제 축: 권한, 승인, 비용, 감사 정책을 통해 에이전트 자율 행동을 관리하고 오작동 및 보안 위협을 원천 차단.

#### 한줄 요약
- **목표 지향성** 기반의 계획·실행·통제 통합 체계 적용

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **대규모 언어 모델(LLM, Large Language Model)**: 자연어 지시와 문맥을 바탕으로 계획, 응답, 행동 후보를 생성하는 에이전트의 추론 엔진. 시스템 자율적 판단의 핵심 요소.
- **오케스트레이터(Orchestrator)**: 목표, 정책, 상태를 기반으로 모델, 계획, 평가, 도구 호출의 순서와 종료를 조정하는 핵심 제어 구성요소.
- **계획 모듈(Planning Module)**: 목표를 의존 관계가 있는 실행 작업으로 분해하고 순서를 수립하는 구성요소. 복잡한 문제 해결의 구조적 완결성을 제공.
- **평가 모듈(Evaluation Module)**: 비용, 완료 조건에 따라 다음 행동의 타당성이나 종료 여부를 판정하는 구성요소. 안정성과 효율성 보장의 핵심 기전.
- **데이터베이스(Database, DB)**: 작업 상태, 실행 결과, 장기 지식을 지속 저장하여 에이전트가 중단된 목표를 이어갈 수 있도록 지원하는 상태 유지 저장소.
- **응용 프로그래밍 인터페이스(API, Application Programming Interface)**: 에이전트가 외부 도구를 정해진 인자, 권한, 응답 형식에 따라 호출하는 통신 인터페이스. 외부 환경 상호작용의 필수 구성.

</details>

```text
               [모델·오케스트레이터]
                         │
              ┌──────────┴──────────┐
              │                     │
          [상태·기억]            [계획·평가]
              │                     │
              └──────────┬──────────┘
                         │
                     [도구·권한]
```

선 의미: 모델·오케스트레이터가 상태·기억 및 계획·평가를 결합하고, 도구·권한 경계가 외부 환경과의 상호작용을 제어하는 에이전트 아키텍처.

| 구성요소 | 책임 |
|:---|:---|
| 모델·오케스트레이터 | LLM과 오케스트레이터 기반 행동 결정 |
| 상태·기억 | 작업 상태·결과·장기 지식 저장 및 유지 |
| 계획·평가 | 작업 분해·비용 및 완료 조건 평가 |
| 도구·권한 | API 스키마 및 권한 정책 기반 실행 |

#### 한줄 요약
- **오케스트레이터** 중심 계획·상태·도구·권한 통합 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **목표·완료 조건·예산 등록(Goal/Budget Registration)**: 작업 범위·금지 행동·종료 기준·자원 한도를 설정하는 단계.
- **현재 상태·기억 제공(Context Provision)**: 이전 행동·결과·장기 지식을 조회하여 판단 맥락 제공.
- **계획 행동·인자·권한 검증 요청(Action Verification Request)**: 도구·순서·인자·위험 행동에 대한 승인 절차.
- **도구 실행 결과·오류 반환(Tool Execution Return)**: 허가된 도구의 실행 결과 및 실패 원인 전달.
- **관찰 결과·완료 판정 저장(Observation Saving)**: 완료·재계획·한도 중단 판단 및 상태 반영.

</details>

```text
오케스트레이터
    │ 1. 목표·완료 조건·예산 등록
    ├───────────────────┐
    │ 완료·중단 전까지   │
    └─────────┬─────────┘
    ▼
상태·기억
    │ 2. 현재 상태·기억 제공
    ▼
오케스트레이터
    │ 3. 계획 행동·인자·권한 검증 요청
    ▼
도구·권한
    │ 4. 도구 실행 결과·오류 반환
    ▼
오케스트레이터
    │ 5. 관찰 결과·완료 판정 저장
    ▼
상태·기억
```

### 동작 원리

1. **목표•완료 조건•예산 등록**: 작업 범위와 금지 행동 및 종료 기준을 설정함.
2. **현재 상태•기억 제공**: 이전 행동과 결과 및 장기 지식을 조회함.
3. **계획 행동•인자•권한 검증 요청**: 다음 도구와 순서를 선택하고 위험 행동 승인을 확인함.
4. **도구 실행 결과•오류 반환**: 허가된 도구를 격리 환경에서 실행함.
5. **관찰 결과•완료 판정 저장**: **ReAct** 반복의 완료•재계획•한도 중단 결과를 상태에 반영함.

#### 한줄 요약
- **계획 행동·인자·권한 검증 요청** 후 실행 및 완료·재계획 판정 체계 적용

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **AI Agent**: 목표 달성을 위해 계획·행동·관찰을 반복하며 외부 도구를 실행하는 자율 시스템.
- **검색 증강 생성(RAG, Retrieval-Augmented Generation)**: 외부 자료를 검색하여 근거 기반 응답을 생성하는 방식.
- **반응형 에이전트(Reactive Agent)**: 장기 계획보다 즉각적인 입력과 규칙에 따라 행동하는 에이전트 유형.

</details>

| 판단 기준 | AI 에이전트 | 전통적 챗봇 | RAG |
|:---|:---|:---|:---|
| 적용 기준 | 다단계 외부 행동 필요 | 단발 질의·안내 필요 | 외부 근거 기반 응답 필요 |
| 핵심 특징 | 계획·행동·관찰 반복 | 단발 대화 응답 중심 | 검색 근거 기반 생성 보강 |
| 한계 | 권한 오용·오류 누적 위험 | 장기 상태·외부 행동 부족 | 검색 밖 행동 실행 불가 |

#### 한줄 요약
- 챗봇은 대화 응답, RAG는 외부 근거 결합, 에이전트는 다단계 도구 실행 적합 기전 적용

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **인간 참여형 통제(HITL, Human-in-the-Loop)**: 고위험 행동 실행 전 사람이 맥락과 영향을 검토하고 승인하는 통제 체계.
- **최소 권한(Least Privilege)**: 작업에 필요한 도구와 데이터만 제한된 범위에서 사용하도록 하는 보안 원칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 도구 권한으로 생기는 외부 피해 | **최소 권한**•인자 스키마•격리 적용 | 오작동 영향 범위 제한 |
| 오류 반복으로 발생하는 비용 폭증 | 재시도•시간•토큰•비용 한도 설정 | 무한 실행 및 자원 낭비 방지 |
| 금액·권리 변경의 책임 불명확 | 금액·권리 변경에 대한 **HITL** 승인 필수 적용 | 책임 있는 자율화 경계 확보 |

#### 한줄 요약
- 금액•권리 변경은 **HITL** 승인 후 실행 체계 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

</details>

- 다단계 외부 행동은 AI 에이전트(AI Agent)를 통해 수행하고, 자산 변경 등 고위험 작업은 인간 참여형 통제(HITL) 승인을 거쳐 실무 안정성을 확보함.

#### 한줄 요약
- **최소 권한**과 **HITL** 경계 기반의 실행 및 비용 검증 체계 적용
