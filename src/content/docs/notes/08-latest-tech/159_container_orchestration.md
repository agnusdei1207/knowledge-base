## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **컨테이너 오케스트레이션(Container Orchestration)**: 다중 호스트의 컨테이너 배포•연결•복구•확장을 하나의 목표 상태에 맞춰 자동 조정하는 운영 개념이다.
- **컨테이너 런타임**: 단일 호스트에서 컨테이너 이미지를 실행하고 생명주기를 관리하는 소프트웨어이다.

</details>

- 정의/개념: 다중 호스트의 컨테이너 배포•연결•확장•복구를 하나의 목표 상태에 맞춰 자동 조정하는 **컨테이너 오케스트레이션 개념**이다.
- 배경/필요성: 개별 컨테이너 런타임만으로는 **분산 상태•장애 복구 통합 조정** 할 수 없다.

#### 한줄 요약

- 여러 지점에 일을 나누고 연결하며 결원이 생기면 대체 인력을 보내는 전체 운영 체계이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **목표 상태**: 실행 수•버전•자원•연결 조건 등 운영자가 선언한 서비스의 원하는 상태이다.
- **서비스 발견**: 동적으로 바뀌는 컨테이너 위치를 찾아 안정된 이름과 주소로 연결하는 기능이다.

</details>

- **상태 축**: 목표 상태 기반 실행 수•버전•자원을 조정한다.
- **배치 축**: 스케줄링•서비스 발견으로 배치•연결한다.
- **복구 축**: 상태 감시 기반 장애 복구•수평 확장이다.

#### 한줄 요약

- 인원과 규칙을 정하면 배치, 안내, 결원 보충, 증원이 자동으로 이어지는 능력이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **스케줄러**: 자원과 제약 조건에 맞는 호스트를 선택해 컨테이너 실행 위치를 정하는 구성요소이다.
- **선언 조정(Reconciliation)**: 사용자가 선언한 목표 상태와 실제 상태의 차이를 반복 감시하고 줄이는 제어 과정이다.
- **노드 실행 계층**: 지정된 호스트에서 컨테이너를 생성•중지하고 상태와 자원 사용량을 보고하는 구성요소이다.
- **서비스 연결 계층**: 변하는 컨테이너 인스턴스에 안정된 주소•발견•부하분산•네트워크 정책을 제공하는 구성요소이다.
- **복구 확장**: 실패나 부하 변화에 따라 컨테이너를 재시작하고 복제 수를 조정하는 기능이다.

</details>

```text
                        [선언 조정]
                       /           \
                 [스케줄러]     [복구 확장]
                      |
                 [노드 실행] ----- [서비스 연결]
```

선의 의미: 선언 조정이 스케줄링과 복구•확장 판단을 함께 통제하고, 스케줄러가 선택한 노드에서 실행된 컨테이너를 서비스 연결 계층이 안정된 주소로 노출하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 선언 조정 | **서비스 요구•현재 상태 차이** 조정 |
| 스케줄러 | **최적 호스트 선택•배치** |
| 노드 실행 | **이미지 수신•컨테이너 실행** 보고 |
| 서비스 연결 | **실행 위치 발견•주소 추상화** |
| 복구 확장 | **실패•부하 기반 재시작•증감** |

#### 한줄 요약

- 기준 장부, 자리 배정자, 현장 실행자, 안내 데스크, 결원•증원 담당자가 연결된 전체 운영 조직과 같음이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **선언 조정기**: 목표 상태와 실제 상태의 차이를 계산해 배치•확장•복구 요청을 만드는 구성요소이다.
- **준비 인스턴스**: 실행을 마치고 서비스 요청을 정상 처리할 수 있다고 판정된 컨테이너이다.

</details>

```text
운영자 ── 목표 상태 요청 ──▶ 선언 조정기
┌──────── 목표 상태와 실제 상태 불일치 시 ────────┐
│ 선언 조정기 ── 1. 배치•확장 요청 전달 ──▶ 스케줄러
│ 스케줄러 ── 2. 호스트 배치 전달 ──▶ 노드 실행기
│ 노드 실행기 ── 3. 준비 인스턴스 전달 ──▶ 서비스 연결
│ 선언 조정기 ◀─ 4. 연결•실행 상태 전달 ─ 서비스 연결
└───────────────────────────────────────────────┘
운영자 ◀── 현재 서비스 상태 ── 선언 조정기
```

1. **배치•확장 요청 전달**: 목표•실제 상태 차이를 계산한다.
2. **호스트 배치 전달**: 자원•제약 기반 실행 위치를 결정한다.
3. **준비 인스턴스 전달**: 컨테이너 실행•준비 상태를 확인한다.
4. **연결•실행 상태 전달**: 서비스 발견•복구 상태를 갱신한다.

#### 한줄 요약

- 목표 인원과 현재 인원을 비교해 배치하고 결원과 수요 증가에 대응한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **쿠버네티스(Kubernetes, K8s)**: 컨테이너 오케스트레이션 개념을 구현한 대표 플랫폼이다.
- **운영체제(Operating System, OS)**: 하드웨어 자원과 응용 실행 환경을 관리하는 시스템 소프트웨어이다.
- **가상머신 관리**: 게스트 운영체제 단위의 강한 격리와 생명주기를 제어하는 운영 방식이다.

</details>

| 운영 방식 | 컨테이너 오케스트레이션 | 단일 호스트 런타임 | 가상머신 관리 |
|:---|:---|:---|:---|
| 적용 기준 | **다중 호스트 분산 서비스** | **한 호스트의 단순 실행** | **강한 격리•레거시 운영** |
| 핵심 특징 | **선언 조정•스케줄•복구** | **로컬 컨테이너 직접 실행** | **게스트 OS 단위 관리** |
| 한계 | **제어면•운영 복잡도 증가** | **다중 호스트 자동 조정 부재** | **큰 이미지•시작 비용** |

> 요약: 다중 호스트는 **오케스트레이션**, 단일 호스트는 **런타임** 중심이 핵심이다.

#### 한줄 요약

- 여러 공장의 작은 작업 상자를 운영하면 오케스트레이션, 한 공장만 쓰면 런타임, 공장 방 전체를 빌리면 가상머신 관리가 맞음이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **상태 감시 루프**: 실제 실행 수•준비 상태•부하를 반복 관측해 목표와의 차이를 찾는 과정이다.
- **주소 추상화**: 컨테이너 위치가 바뀌어도 동일한 서비스 이름과 가상 주소로 접근하게 하는 기능이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 목표•실제 상태 차이로 **복제본 불일치** | 선언 조정•상태 감시 루프 적용 | 서비스 **실행 수 일관성** 확보 |
| 위치 변경으로 **서비스 주소 단절** | 서비스 발견•주소 추상화 적용 | 동적 배치의 **연결 연속성** 확보 |

#### 한줄 요약

- 먼저 여러 지점 운영 능력이 필요한지 판단하고, 필요할 때 K8s를 구현체로 고르며 한 지점이면 단순 도구를 쓰는 것이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **다중 호스트**: 컨테이너 실행 자원을 제공하도록 하나의 운영 체계로 묶은 여러 서버이다.
- **동적 상태**: 장애•배포•부하 변화에 따라 컨테이너 수와 위치가 계속 달라지는 운영 상태이다.

</details>

- 다중 호스트•동적 상태는 **오케스트레이션**, 단일 호스트는 **런타임**을 선택한다.

#### 한줄 요약

- 여러 서버의 컨테이너를 한 기준으로 배치•복구한다.
