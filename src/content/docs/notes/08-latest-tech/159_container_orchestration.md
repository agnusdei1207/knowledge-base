## 미리 알고가기

- **컨테이너 오케스트레이션(Container Orchestration)**: 다중 호스트의 컨테이너 배포·연결·복구·확장을 자동 조정하는 운영 개념
- **오케스트레이션(Orchestration)**: 여러 실행·네트워크·복구 기능을 하나의 목표 상태에 맞춰 조율
- **Kubernetes(쿠버네티스)**: 컨테이너 오케스트레이션 개념을 구현한 대표 플랫폼



## Ⅰ. 개요

- 정의/개념: 다중 호스트의 **배치·연결·확장·복구**를 자동 조정하는 운영 체계
- 배경/필요성: 개별 런타임의 **분산 상태·장애 복구 조정** 한계 해소 필요

### 쉽게 이해하기 (학습용)

- 여러 지점에 일을 나누고 연결하며 결원이 생기면 대체 인력을 보내는 전체 운영 체계임

## Ⅱ. 특징

- 목표 상태 기반 **실행 수·버전·자원 조정**
- 스케줄링·서비스 발견 기반 **배치·연결 자동화**
- 상태 감시 기반 **장애 복구·수평 확장**

### 쉽게 이해하기 (학습용)

- 인원과 규칙을 정하면 배치, 안내, 결원 보충, 증원이 자동으로 이어지는 능력임

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 1
  A["선언 조정"]
  B["스케줄러"]
  C["노드 실행"]
  D["서비스 연결"]
  E["복구 확장"]
  A --- B
  B --- C
  C --- D
  A --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 선언 조정 | 서비스 요구 사항과 현재 상태의 차이 조정 |
| 스케줄러 | 최적 호스트 선택 및 배치 |
| 노드 실행 | 이미지 수신·컨테이너 실행 및 보고 |
| 서비스 연결 | 실행 위치 발견 및 주소 추상화 |
| 복구 확장 | 실패·부하에 따른 재시작 및 증감 수행 |

> 요약: 선언 상태에 따라 스케줄링·서비스·복구를 조정한다.

### 쉽게 이해하기 (학습용)

- 기준 장부, 자리 배정자, 현장 실행자, 안내 데스크, 결원·증원 담당자가 연결된 전체 운영 조직과 같음

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant U as 운영자
    participant R as 선언 조정기
    participant S as 스케줄러
    participant N as 노드 실행기
    participant D as 서비스 연결
    U->>R: 1. 목표 상태 전달
    R->>S: 2. 배치·확장 요청 전달
    S->>N: 3. 호스트 배치 전달
    N->>D: 4. 준비 인스턴스 전달
    D-->>R: 5. 연결·실행 상태 전달
```

### 동작 원리

- **1. 목표 상태 전달**: 버전·복제 수·자원·연결 정책 등록
- **2. 배치·확장 요청 전달**: 목표와 실제 상태 차이 계산
- **3. 호스트 배치 전달**: 자원·제약 기반 실행 위치 결정
- **4. 준비 인스턴스 전달**: 컨테이너 실행과 상태 확인
- **5. 연결·실행 상태 전달**: 서비스 발견·복구·확장 루프 갱신

> 요약: 목표와 실제 상태의 차이를 배치·연결·복구로 조정한다

### 쉽게 이해하기 (학습용)

- 목표 인원과 현재 인원을 비교해 배치하고 결원과 수요 증가에 대응한다.

## Ⅴ. 종류 및 비교

| 운영 방식 | 컨테이너 오케스트레이션 | 단일 호스트 런타임 | 가상머신 관리 |
|:---|:---|:---|:---|
| 적용 기준 | 다중 호스트 분산 서비스 | 한 호스트의 단순 실행 | 강한 격리·레거시 운영 |
| 핵심 특징 | 선언 조정·스케줄·복구 | 로컬 컨테이너 직접 실행 | 게스트 OS 단위 자원 관리 |
| 한계 | 제어면과 운영 복잡도 증가 | 다중 호스트 자동 조정 부재 | 큰 이미지와 시작 비용 |

> 요약: 관리 범위로 오케스트레이션·런타임·가상머신을 구분한다.

### 쉽게 이해하기 (학습용)

- 여러 공장의 작은 작업 상자를 운영하면 오케스트레이션, 한 공장만 쓰면 런타임, 공장 방 전체를 빌리면 가상머신 관리가 맞음

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 목표·실제 상태 차이로 **복제본 불일치** | 선언 조정·상태 감시 루프 적용 | 서비스 **실행 수 일관성** 확보 |
| 위치 변경으로 **서비스 주소 단절** | 서비스 발견·주소 추상화 적용 | 동적 배치의 **연결 연속성** 확보 |

### 쉽게 이해하기 (학습용)

- 먼저 여러 지점 운영 능력이 필요한지 판단하고, 필요할 때 Kubernetes를 구현체로 고르며 한 지점이면 단순 도구를 쓰는 것임

## Ⅶ. 결론

- **호스트 규모·상태 조정·연결 변화**로 오케스트레이션 도입 범위를 결정

### 쉽게 이해하기 (학습용)

- 여러 서버의 컨테이너를 한 기준으로 배치·복구한다
