## 미리 알고가기

- **Smart Contract**: 블록체인에서 조건 충족 시 상태 전이를 자동 실행하는 프로그램
- **적용**: 법률 전체 대체보다 합의된 조건의 디지털 자동 집행에 적합함
- **리스크**: 코드 취약점, oracle 의존성 및 업그레이드 거버넌스가 핵심임



## Ⅰ. 개요

- **정의/개념**: 블록체인에서 결정적 상태 전이를 수행하는 코드
- **배경/필요성**: 중앙 운영자 없이 합의 규칙을 자동 집행

### 쉽게 이해하기 (학습용)

- 서명된 요청을 받아 지정된 규칙으로 자판기처럼 결과를 도출함

## Ⅱ. 특징

- 결정적 실행이 노드별 상태 합의를 보장한다.
- 가스 한도가 자원 남용과 무한 실행을 제한한다.
- 오라클 신뢰가 외부 정보의 정확성을 좌우한다.
- 업그레이드·키 통제가 불변 코드 위험을 보완한다.

### 쉽게 이해하기 (학습용)

- 코드 수정이 어렵고, 외부 정보는 전달자를 신뢰해야 하는 특성이 있음

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 명세/코드 | 계약 로직 및 상태 변수 구현 |
| VM/가스 | 결정적 실행 환경 및 자원 제한 |
| 접근/외부 | reentrancy 제어 및 외부 호출 관리 |
| 거버넌스 | 업그레이드 정책 및 배포 관리 |

[구조]
  └─ 트랜잭션 → VM 실행 → 상태 변경

> 요약: 서명 요청을 가스 한도에서 실행해 상태 전이

### 쉽게 이해하기 (학습용)

- 사용자가 요청하면 규칙대로 계산하고 결과 장부를 업데이트함

## Ⅳ. 원리 및 절차 흐름도

```text
호출제출
  ↓
실행검증
  ↓
결정실행
  ↓
상태확정
```

| 절차 | 설명 |
|:---|:---|
| 호출제출 | 서명된 요청을 블록체인에 전송함 |
| 실행검증 | 서명과 가스 한도를 확인하고 컨텍스트 제공함 |
| 결정실행 | 동일한 규칙으로 결과를 계산함 |
| 상태확정 | 성공 시 장부 반영, 실패 시 되돌림 |

> 요약: 요청을 결정적으로 실행하고 결과에 따라 장부를 반영함

### 쉽게 이해하기 (학습용)

- 검증자가 동일 규칙으로 결과를 확인한 뒤, 성공 시만 장부를 수정함

## Ⅴ. 종류 및 비교

| 판단 기준 | 법률 계약 | 스마트 계약 | 중앙 업무 시스템 |
|:---|:---|:---|:---|
| 핵심 특징 | 법원 및 기관 | 블록체인 자동화 | 시스템 운영자 |
| 적용 기준 | 신원·증거 신뢰 | consensus 기반 | 조직 통제 신뢰 |
| 주요 위험 | 해석 및 소송 | 코드 기반 불변성 | 운영자 수정/복구 |

> 요약: 온체인 집행과 외부 정보 거버넌스를 분리

### 쉽게 이해하기 (학습용)

- 법률은 전체를, 스마트 계약은 자동 집행을, 중앙은 회사가 담당함

## Ⅵ. 실무 사례

1. **대출 서비스**: 가격 오라클 연동 및 재진입 공격 방어 조치함
2. **공급망 에스크로**: 검수 등 현실 절차는 외부 서명으로 연동함

### 쉽게 이해하기 (학습용)

- 대출 서비스: 가격 오라클 연동 및 재진입 공격 방어 조치함
- 공급망 에스크로: 검수 등 현실 절차는 외부 서명으로 연동함

## Ⅶ. 결론

- 오라클·업그레이드·키 통제로 자동 집행 범위 결정

### 쉽게 이해하기 (학습용)

- 자동 실행을 넘어 외부 정보와 관리 권한을 함께 설계해야 함
