## 미리 알고가기

- **임베딩(Embedding)**: 단어·문장·이미지 같은 대상을 의미나 특징이 가까울수록 인접하도록 연속 벡터 공간에 배치한 표현
- **인코더(Encoder)**: 입력을 문맥과 특징이 반영된 벡터 표현으로 변환하는 모델
- **풀링(Pooling)**: 여러 토큰 벡터를 평균·최대·특수 토큰 방식으로 결합해 고정 길이 벡터를 만드는 연산
- **코사인 유사도(Cosine Similarity)**: 두 벡터가 이루는 각도를 이용해 방향의 유사성을 측정하는 지표
- **벡터 정규화(Vector Normalization)**: 벡터 크기의 영향을 통제하도록 길이를 일정하게 맞추는 처리
- **상위 k개 재현율(Recall@k)**: 관련 정답 중 상위 k개 검색 결과에 포함된 비율
- **정규화 할인 누적 이득(normalized Discounted Cumulative Gain, nDCG)**: 관련성과 순위 위치를 함께 반영한 검색 품질 지표



## Ⅰ. 개요

- 정의/개념: 입력의 의미·특징을 연속 공간의 **고정 길이 벡터**로 표현하는 방식
- 배경/필요성: 원시 텍스트·이미지는 형태·길이가 달라 **의미 거리 비교** 불가

### 쉽게 이해하기 (학습용)

- 글이나 그림을 서로 비교할 수 있는 고정 길이 좌표로 변환합니다.

## Ⅱ. 특징

![의미가 비슷한 표현의 임베딩 공간 배치](/study/diagrams/embedding-semantic-space.svg)

> 파란 검색 표현과 붉은 보안 표현은 각 주제 안에서 가깝게 모이고 서로 다른 주제 사이는 멀어지며, 실제 모델 출력이 아닌 의미 거리의 개념 좌표다.

- 벡터에 보존할 의미·특징을 정하는 **인코더 학습 목표**
- 가변 입력을 검색 벡터로 바꾸는 **풀링·고정 차원화**
- 모델·차원·정규화·거리 함수의 **표현 공간 일관성**

### 쉽게 이해하기 (학습용)

- 같은 차원이라도 모델과 거리 규격이 다르면 비교할 수 없고 큰 차원이 품질을 보장하지 않습니다.

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 3
  preprocessor["전처리기"]
  encoder["인코더"]
  pooler["풀링기"]
  registry["벡터 규격 저장소"]
  similarity["유사도 계산기"]
  preprocessor --- encoder
  encoder --- pooler
  pooler --- registry
  registry --- similarity
```

| 구성요소 | 책임 |
|:---|:---|
| **전처리기** | 입력을 모델 토큰 규격으로 변환 |
| **인코더** | 문맥·특징을 토큰 벡터로 변환 |
| **풀링기** | 토큰 벡터를 고정 길이로 결합 |
| **벡터 규격 저장소** | 모델·차원·정규화·풀링 버전 관리 |
| **유사도 계산기** | 동일 규격 벡터 거리·유사도 산출 |

### 쉽게 이해하기 (학습용)

- 전처리·인코더·풀링으로 비교 가능한 벡터를 만듭니다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
  participant P as 전처리기
  participant E as 인코더
  participant O as 풀링기
  participant R as 벡터 규격 저장소
  participant S as 유사도 계산기
  P->>E: 1. 토큰 규격 입력
  E->>O: 2. 문맥 토큰 벡터
  O->>R: 3. 고정 길이 벡터·규격
  R->>S: 4. 동일 규격 비교 요청
  S-->>R: 거리·유사도 결과
```

**동작 원리**

1. **토큰 규격 입력**: 모델 버전에 맞춰 입력 단위를 통일
2. **문맥 토큰 벡터**: 인코더가 입력 특징을 연속 공간에 배치
3. **고정 길이 벡터·규격**: 풀링 결과와 생성 규격을 함께 등록
4. **동일 규격 비교 요청**: 모델·차원·정규화가 같은 벡터만 선택

### 쉽게 이해하기 (학습용)

- 같은 규격으로 벡터를 만들고 실제 검색·분류 과제로 평가합니다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 희소 표현 | 정적 임베딩 | 문맥 임베딩 |
|:---|:---|:---|:---|
| **적용 기준** | **정밀 검색** | **어휘 유사도** | 문맥·**다의어 구분** |
| **핵심 특징** | 단어별 **희소 차원** | 단어별 **고정 밀집 벡터** | 문맥별 **토큰·문장 벡터** |
| **한계** | 표기 변형·**동의어 누락** | 다의어·**문맥 구분 한계** | 생성·저장·**검색 비용 증가** |

### 쉽게 이해하기 (학습용)

- 희소·정적·문맥 임베딩은 표현 범위와 계산 비용이 다릅니다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 규격이 다른 **벡터 공간** 혼합 | 버전·전처리·차원·풀링을 함께 등록 | **거리 비교 정합성** 확보 |
| 학습 목적과 **거리 함수** 불일치 | 권장 거리 함수와 **정규화** 고정 | **유사도 순위** 보존 |
| 전문 용어·다의어의 **표현력 부족** | **Recall@k·nDCG** 평가 후 미세조정 | **검색 누락률** 감소 |

### 쉽게 이해하기 (학습용)

- 생성 규격을 고정하고 실제 질문과 정답 자료로 업무 의미를 구분하는지 검증합니다.

## Ⅶ. 결론

- 정밀 용어는 **희소 표현**, 문맥·다의어는 **문맥 임베딩**을 선택

### 쉽게 이해하기 (학습용)

- 같은 생성 규격과 거리 함수를 유지하고 실제 과제로 의미 표현 품질을 확인해야 합니다.
