## 미리 알고가기

- **임베딩(Embedding, 임베딩)**: 대상을 벡터 공간에 끼워 넣는다는 뜻으로, 입력 특징을 거리 비교 가능한 수치 벡터로 변환
- **인코더 (Encoder)**: 입력 특징을 벡터로 변환하는 모델
- **풀링 (Pooling)**: 토큰 벡터를 고정 길이 벡터로 결합함
- **거리 함수 (Distance Function)**: 벡터 간 유사도를 계산함



## Ⅰ. 개요

- **정의/개념**: 입력의 의미·특징을 고정 길이 벡터로 표현
- **기존 한계**: 원문·이미지는 형태와 길이가 달라 직접 거리 비교 곤란
- **배경/필요성**: 입력 특징을 공통 벡터 공간에서 비교

### 쉽게 이해하기 (학습용)

- 글이나 그림을 서로 비교할 수 있는 고정 길이 좌표로 변환합니다.

## Ⅱ. 특징

- 인코더의 학습 목표가 벡터에 보존할 의미·특징을 정한다.
- 풀링으로 가변 길이 입력을 고정 차원 벡터로 변환한다.
- 같은 모델 버전·차원·정규화·거리 함수로 벡터를 비교한다.

### 쉽게 이해하기 (학습용)

- 같은 차원이라도 모델과 거리 규격이 다르면 비교할 수 없고 큰 차원이 품질을 보장하지 않습니다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 핵심 키워드 | 직관적 설명 |
|:---|:---|:---|
| 전처리 | 토큰 분할 | 입력을 변환 가능한 형식으로 정제함 |
| 인코더 | 모델 매핑 | 특성을 벡터 공간에 배치함 |
| 풀링 | 결합 방식 | 토큰을 고정 벡터로 통합함 |
| 벡터 규격 | 버전·차원 | 데이터 표현 방식을 정의함 |
| 거리 함수 | 유사도 계산 | 벡터 간 가까움을 수치화함 |

```text
원본입력
├─ 전처리기
├─ 인코더
├─ 풀링방식
├─ 벡터규격
└─ 거리함수
```

### 쉽게 이해하기 (학습용)

- 전처리·인코더·풀링으로 비교 가능한 벡터를 만듭니다.

## Ⅳ. 원리 및 절차 흐름도

```text
입력규격
↓
벡터생성
↓
비교설정
↓
과제평가
↓
버전등록
```

| 절차 | 설명 |
|:---|:---|
| 입력규격 | 전처리를 통일함 |
| 벡터생성 | 고정 벡터 생성함 |
| 비교설정 | 정규화·함수 고정함 |
| 과제평가 | 목표 과제로 검증함 |
| 버전등록 | 처리 규격 등록함 |

### 쉽게 이해하기 (학습용)

- 같은 규격으로 벡터를 만들고 실제 검색·분류 과제로 평가합니다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 희소 표현 | 정적 임베딩 | 문맥 임베딩 |
|:---|:---|:---|:---|
| 적용 기준 | 정밀 검색 | 어휘 유사도 | 문맥·다의어 구분 |
| 핵심 특징 | 단어별 희소 차원 | 단어별 고정 밀집 벡터 | 문맥별 토큰·문장 벡터 |
| 한계 | 표기 변형·동의어 누락 | 다의어·문맥 구분 한계 | 생성·저장·검색 비용 증가 |

> 요약: 데이터 표현 방식에 따른 차이임

### 쉽게 이해하기 (학습용)

- 희소·정적·문맥 임베딩은 표현 범위와 계산 비용이 다릅니다.

## Ⅵ. 실무 사례

- 동일 임베딩 규격의 관련 문서 회수율로 모델 선택
- 도메인 검증셋으로 장애 로그 분류 결과 비교

### 쉽게 이해하기 (학습용)

- 실제 질문과 정답 자료로 어떤 임베딩이 업무 의미를 가장 잘 구분하는지 검증합니다.

## Ⅶ. 결론

- 규격을 일치시키고 과제별 평가로 모델을 선정함

### 쉽게 이해하기 (학습용)

- 같은 생성 규격과 거리 함수를 유지하고 실제 과제로 의미 표현 품질을 확인해야 합니다.
