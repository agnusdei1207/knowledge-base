## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **오픈텔레메트리(OpenTelemetry, OTel)**: 텔레메트리를 생성•처리•전송하기 위한 공급자 중립 오픈소스 관찰 가능성 프레임워크이다.
- **공급자 중립**: 특정 관측 백엔드 제품에 종속되지 않는 공통 계측•전송 계약을 제공하는 성질을 말한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 코드가 텔레메트리를 생성할 때 사용하는 계약이다.
- **소프트웨어 개발 키트(Software Development Kit, SDK)**: API 신호를 샘플링•가공•내보내는 구현체을 의미한다.
- **오픈텔레메트리 프로토콜(OpenTelemetry Protocol, OTLP)**: 프로세스와 Collector 사이의 표준 신호 전송 규약을 의미한다.

</details>

- 정의: 공급자 중립 텔레메트리 생성•전송 체계 **OTel**이다.
- 배경/필요성: 제품별 계측으로 **언어•백엔드 종속•중복** 발생

#### 한줄 요약

- 공통 계측•전송 계약으로 **계측•백엔드 분리** ## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **맥락 전파**: 서비스 경계를 넘어 추적 식별자와 부가 정보를 전달하는 과정을 말한다.
- **시맨틱 규약**: 서비스•요청•자원 속성의 이름과 의미를 일관되게 정의한 규칙을 의미한다.

</details>

- 계측 생성 계약과 처리 정책을 분리하는 **API•SDK 분리** 핵심임.
- 맥락 전파와 시맨틱 규약 기반 **맥락•의미 표준화** 핵심임.
- OTLP•Collector 기반 **중립 전송 파이프라인** 핵심임.

#### 한줄 요약

- 측정 방법, 자료 포장법, 항목 이름, 운송 규격을 통일하되 최종 분석 백엔드는 분석 목적에 맞게 선택한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **API 계측 계약**: 언어별 코드가 메트릭•로그•추적을 생성하는 접점을 의미한다.
- **SDK 처리 정책**: 신호의 샘플링•자원 결합•일괄 처리•내보내기를 제어하는 정책로 정의된다.
- **Collector**: 텔레메트리를 수신해 처리하고 하나 이상의 저장•분석 백엔드로 전달하는 독립 구성요소로 정의된다.
- **맥락 전파**: 신호 사이의 요청 관계를 유지하도록 식별자를 전달하는 개념을 의미한다.
- **시맨틱 규약**: 서비스•요청•자원 속성의 이름과 의미를 통일하는 개념이다.

</details>

```text
                    [맥락 전파]   [시맨틱 규약]
                          \       /
                            [API]
                              |
                            [SDK]
                              |
                            [OTLP]
                              |
                         [Collector]
```
선의 의미: 맥락 전파와 시맨틱 규약은 API의 요청 관계와 속성 의미를 표준화하고, SDK는 API 신호의 처리 정책을 구현하며 OTLP는 SDK와 Collector 사이의 공급자 중립 전송 경계를 제공한다.

| 구성요소 | 책임 |
|:---|:---|
| API | 코드의 스팬•메트릭•로그 생성 계약 제공 |
| SDK | 샘플링•자원 결합•일괄 처리•내보내기 실행 |
| 맥락 전파 | 신호 사이의 요청 상관관계 유지 |
| 시맨틱 규약 | 신호 속성의 이름과 의미 통일 |
| OTLP | 프로세스와 Collector 사이의 표준 신호 전송 |
| Collector | 신호 수신•변환•필터링•라우팅•내보내기 |

#### 한줄 요약

- 측정 계약과 처리 장치가 공통 이름표를 붙인 자료를 표준 운송 규격으로 집하장에 보내는 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **OTLP 전송**: OTel 신호를 프로세스와 Collector 사이에서 표준 형식으로 전달하는 개념을 말한다.
- **내보내기 모듈(Exporter)**: 처리한 텔레메트리를 OTLP나 백엔드별 프로토콜로 전송하는 구성요소이다.

</details>

API로 생성한 신호를 SDK가 처리하고 OTLP로 전송한다.

```text
애플리케이션
   │ 1. 신호 생성
   ▼
SDK
   │ 2. 신호 처리
   │ 3. OTLP 표준 전송
   ▼
Collector
   │ 4. 신호 라우팅
   ▼
백엔드
```

### 동작 원리

1. 신호 생성: API•시맨틱 규약으로 텔레메트리 생성
2. 신호 처리: SDK가 자원 결합•샘플링•일괄 처리
3. OTLP 표준 전송: Exporter가 Collector에 신호 전달
4. 신호 라우팅: Collector가 변환•필터링 후 백엔드 전송

#### 한줄 요약

- 애플리케이션이 공통 계약으로 신호를 만들면 SDK와 Collector가 이를 처리해 원하는 분석 백엔드로 보냅니다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **계측 코드**: 애플리케이션의 연산•요청•상태에서 텔레메트리를 생성하도록 추가한 코드을 말한다.
- **수집 파이프라인**: 신호를 수신•변환•필터링•라우팅해 백엔드로 전달하는 처리 경로을 말한다.

</details>

API, SDK, Collector는 신호 생성•처리•수집을 분담한다.

| 구분 | API | SDK | Collector |
|:---|:---|:---|:---|
| 적용 기준 | 애플리케이션 **계측 코드** | 애플리케이션 **실행 프로세스** | 중앙•에이전트형 **수집 파이프라인** |
| 핵심 특징 | 공급자 중립 **신호 생성 계약** | **샘플링•처리•내보내기** 구현 | **수신기•처리기•내보내기** 조합 |
| 주요 한계 | 단독 **신호 처리 불가** | **프로세스 자원•설정** 영향 | 용량 부족 시 **병목•데이터 손실** |

#### 한줄 요약

- API는 생성 계약, SDK는 프로세스 안의 처리, Collector는 중앙 수집•변환•전송을 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **카디널리티 예산**: 저장•질의 비용 한도 안에서 허용할 속성 고유 값 수를 정한 기준을 의미한다.
- **영속 버퍼**: Collector 장애나 백엔드 지연에도 신호를 잃지 않도록 디스크 등에 임시 보관하는 큐을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 맥락 전파 단절로 **호출 경로 유실** | 전파 형식 통일•경계별 **식별자 전달 시험** | **분산 추적 연속성** 확보 |
| 속성 규약 불일치로 **질의 분산•비용 증가** | 규약 버전•속성 허용 목록•**카디널리티 예산** | **질의 일관성•비용 예측성** 향상 |
| Collector 과부하로 **텔레메트리 손실** | 용량 시험•재시도 큐•**영속 버퍼•신호 우선순위** | **핵심 신호 보존율** 향상 |

#### 한줄 요약

- 속성 이름과 추적 맥락을 통일하고 Collector 용량을 시험해야 백엔드를 바꿔도 신호 품질이 유지됩니다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **계측•백엔드 분리**: 애플리케이션의 신호 생성 계약을 유지한 채 저장•분석 제품을 바꿀 수 있게 하는 설계을 말한다.
- **핵심 신호 보존율**: 수집 부하와 장애 상황에서도 우선순위가 높은 텔레메트리가 백엔드에 도달한 비율로 정의된다.

</details>

- 다중 백엔드•언어 환경은 **OTel**, 단일 제품 전용은 **자체 계측** 선택

#### 한줄 요약

- **계측•백엔드 분리•핵심 신호 보존율** 보장할 때 적용
