## 미리 알고가기

- **OpenTelemetry(OTel)**: '오픈텔레메트리', 약칭은 '오텔'로 읽으며, 텔레메트리 생성·수집·내보내기를 위한 벤더 중립 관측성 프레임워크
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: '에이피아이'로 읽으며, 계측 호출과 문맥 전파 계약을 정의
- **소프트웨어 개발 키트(Software Development Kit, SDK)**: '에스디케이'로 읽으며, API의 신호 처리·내보내기 동작을 구현
- **OpenTelemetry Protocol(OTLP)**: '오티엘피'로 읽으며, 텔레메트리 전송 형식을 규정한 프로토콜
- **Collector**: '컬렉터'로 읽으며, 신호를 수신·가공·분기·전송하는 별도 구성요소
- **Semantic Conventions**: '시맨틱 컨벤션'으로 읽으며, 신호 속성과 이름의 공통 의미 규칙

## Ⅰ. 개요

- 정의/개념: 텔레메트리의 생성·수집·내보내기를 위한 **벤더 중립 API·SDK·프로토콜·도구 체계**
- **배경/필요성**: 제품별 에이전트와 속성 체계의 **언어·백엔드 종속 및 중복 계측 한계를 해소**하기 위해 필요

### 쉽게 이해하기 (학습용)

- OpenTelemetry는 관측 데이터를 만드는 공용 계측·운송 체계이며, 데이터를 저장하고 화면에 보여 주는 백엔드는 아니다.

## Ⅱ. 특징

- API는 계측 계약, SDK는 **신호 처리·내보내기 구현**을 담당한다.
- 문맥 전파와 의미 규칙으로 **서비스 간 요청 관계와 속성 의미를 통일**한다.
- OTLP와 Collector로 신호를 전송·가공하지만 **저장·질의 백엔드는 포함하지 않는다**.

### 쉽게 이해하기 (학습용)

- API는 규격, SDK는 실행 부품, OTLP는 운송 규칙, Collector는 분류소다.

## Ⅲ. 아키텍처 및 구성요소

```text
앱 계측 → API·SDK → OTLP → Collector → 관측 백엔드
```

| 설계 요소 | 설명 |
|:---|:---|
| API | **계측 호출·문맥 전파 계약** |
| SDK | **신호 처리·표본화·내보내기** |
| OTLP | **텔레메트리 전송 규격** |
| Collector | **수신·가공·분기·재전송** |
| 의미 규칙 | **공통 속성·명명 체계** |
| 관측 백엔드 | **저장·질의·시각화 담당** |

> 요약: API·SDK가 계측하고 OTLP·Collector가 신호를 백엔드로 전달한다.

### 쉽게 이해하기 (학습용)

- Collector까지는 공용 운송 체계이고 저장·검색·화면은 선택한 백엔드가 맡는다.

## Ⅳ. 원리 및 절차 흐름도

```text
의미 계약 선정 → 계측 삽입 → SDK 처리 → OTLP 전송 → Collector 처리 → 백엔드 활용
```

| 절차 | 설명 |
|:---|:---|
| 의미 계약 선정 | 신호·속성·규칙 버전 결정 |
| 계측 삽입 | 자동·수동 계측과 문맥 전파 |
| SDK 처리 | 자원·샘플·배치 정책 적용 |
| OTLP 전송 | SDK에서 Collector로 전송 |
| Collector 처리 | 필터·변환·분기·재시도 |
| 백엔드 활용 | 저장·질의 결과로 계측 개선 |

> 요약: 공통 의미로 계측한 신호를 SDK와 Collector가 처리해 백엔드로 보낸다.

### 쉽게 이해하기 (학습용)

- 질문에 필요한 이름과 속성을 정한 뒤 공용 운송 규칙과 분류소를 거쳐 분석 시스템으로 보낸다.

## Ⅴ. 종류 및 비교

| OpenTelemetry 구성 책임 | API | SDK | Collector |
|:---|:---|:---|:---|
| 적용 기준 | 구현 독립 계측 호출 | 앱별 처리 정책 구현 | 중앙 가공·다중 전송 |
| 핵심 특징 | 계측·문맥 전파 계약 | 표본화·배치·내보내기 | 수신·변환·분기 |
| 한계 | 단독으로 신호 처리 불가 | 앱 자원·설정 부담 | 운영·용량 관리 필요 |

> 요약: API는 계약, SDK는 앱 내부 처리, Collector는 앱 외부 처리를 담당한다.

### 쉽게 이해하기 (학습용)

- 역할을 나누면 계측 코드를 유지하면서 처리 정책이나 저장 백엔드를 바꿀 수 있다.

## Ⅵ. 실무 사례

1. **다언어 서비스의 공통 속성·문맥 계측**

### 쉽게 이해하기 (학습용)

- 여러 언어의 서비스가 같은 이름과 속성으로 요청을 기록한다.

## Ⅶ. 결론

- 벤더 종속 없이 일관된 텔레메트리를 수집하기 위해 **의미 규약·문맥 전파·Collector·민감정보·표본·백엔드 책임**을 검토하고, OpenTelemetry로 계측과 전송을 표준화한다.

### 쉽게 이해하기 (학습용)

- 공용 배관과 저장·분석 시스템을 나누면 백엔드 선택권을 유지할 수 있다.
