## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 가드레일(Agent Guardrail)**: 에이전트의 입력•출력•도구 행동에서 발생하는 위험을 탐지하고 제한하는 통제 체계이다.
- **행동 위험(Action Risk)**: 모델의 판단이 외부 도구 호출이나 상태 변경으로 이어져 실제 피해를 일으킬 가능성.

</details>

- 정의/개념: 입력•출력•도구 행동을 제한하는 **가드레일**
- 배경/필요성: AI 에이전트가 웹 브라우징, 이메일, 문서 파싱 등을 통해 외부 비신뢰 데이터(Untrusted Data)를 소비할 때, 간접 프롬프트 주입(Indirect Prompt Injection), 악성 탈옥(Jailbreak), 민감 데이터 유출 및 비인가 시스템 조작 공격에 무방비로 노출되는 치명적인 보안 취약점이 존재함에 따라, 입력, 런타임 추론, 도구 실행, 최종 출력의 전 단계에 걸쳐 다계층 정책 필터를 강제하는 에이전트 가드레일(Agent Guardrail) 아키텍처를 도입하여 **심층 방어(Defense in Depth) 기반의 입력 악성 지시 사전 차단, 신뢰 지시와 외부 비신뢰 데이터의 엄격한 권한 분리(Privilege Separation), 도구 호출 직전 인자 검증 및 트립와이어(Tripwire)/HITL 기반의 비가역 피해 원천 방어**를 달성할 필요

#### 한줄 요약

- **입력•도구•출력 가드레일**은 겹겹이 둘수록 위험 행동을 막지만 정상 요청의 오차단과 지연도 함께 늘므로, 차단 강도는 오탐 허용치와 사고 비용의 비교로 정한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **심층 방어(Defense in Depth)**: 하나의 통제가 우회되더라도 피해를 막도록 독립된 통제를 여러 계층에 배치하는 원칙으로 정의된다.
- **프롬프트 주입(Prompt Injection)**: 외부의 비신뢰 데이터에 숨긴 지시로 모델의 원래 통제와 목표를 우회하는 공격으로 정의된다.
- **트립와이어(Tripwire)**: 금지 조건이나 위험 징후가 검출되면 실행을 즉시 중단시키는 조건.
- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 도구 행동을 사람이 검토한 뒤 승인•수정•거부하는 통제로 정의된다.
- **위험 기반 대응(Risk-based Response)**: 탐지 수준에 따라 요청을 허용•수정•격리•차단하거나 사람에게 이관하는 방식이다.

</details>

- **심층 방어**: 독립 통제를 여러 실행 경계에 배치
- **프롬프트 주입 방어**: 비신뢰 지시를 별도 계층에서 검사
- **트립와이어**: 금지 조건 검출 시 실행 중단
- **위험 기반 대응**: 위험도별 허용•수정•차단
- **HITL**: 고위험 행동을 사람이 검토•승인
- **임계치 관리**: 오탐•미탐•우회율 상충 평가

#### 한줄 요약

- 위험도에 따라 **허용•수정•차단•HITL 이관** 결정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **비신뢰 데이터(Untrusted Data)**: 모델이 참고할 수는 있지만 명령 권한을 부여해서는 안 되는 외부 문서•웹페이지•도구 결과.
- **에이전트 런타임(Agent Runtime)**: 신뢰 지시와 비신뢰 데이터를 분리하고 정책에 따라 모델•메모리•도구 실행을 조정하는 계층.

</details>

```text
                  [입력 검사기]
                        |
               [에이전트 런타임]
                        |
               [도구 정책 집행기]
                        |
                  [출력 검사기]
```

선의 의미: 에이전트 런타임을 중심으로 입력, 도구 실행, 출력의 독립된 검사 경계가 중첩되는 심층 방어 구조를 뜻함.

| 구성요소 | 책임 |
|:---|:---|
| 입력 검사기 | 악성 지시•민감정보를 **사전 검출** |
| 에이전트 런타임 | 신뢰 지시와 **비신뢰 데이터** 분리 |
| 도구 정책 집행기 | 실행 전 인자•권한•**부작용** 판정 |
| 출력 검사기 | 유해성•민감정보•**정책 위반** 검출 |

#### 한줄 요약

- 입력•런타임•도구•출력에 **심층 방어** 적용

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **명령 권한 분리(Privilege Separation)**: 시스템과 사용자의 신뢰 지시는 따르되 외부 콘텐츠의 문장은 실행 명령으로 취급하지 않는 통제.
- **입력 위험•민감정보 검사(Input Risk/Sensitivity Validation)**: 사용자 입력에서 악성 지시•난독화•비밀정보를 찾아내는 절차.
- **신뢰 지시•비신뢰 문맥 분리(Trusted Instruction/Untrusted Context Separation)**: 외부 콘텐츠를 데이터로만 취급해 명령 권한을 제거하는 절차로 정의된다.
- **도구 인자•권한•부작용 검증(Tool Argument/Privilege/Side-effect Validation)**: 도구 호출 직전에 요청 주체•인자•권한과 예상 피해를 판정하는 절차.
- **정책 판정 집행(Policy Execution)**: 위험 수준에 따라 도구 요청을 허용•수정•격리•차단•이관하는 절차로 정의된다.
- **출력 정책 검사(Output Policy Validation)**: 외부 전달 전에 유해성•민감정보•정책 위반을 다시 확인하는 절차로 정의된다.

</details>

```text
사용자
   │ 사용자 요청
   ▼
입력 검사기
   │ 1. 입력 위험•민감정보 검사
   │ 검사된 입력 전달
   ▼
에이전트
   │ 2. 신뢰 지시•비신뢰 문맥 분리
   │ 도구 실행 요청
   ▼
도구 정책 집행기
   │ 3. 도구 인자•권한•부작용 검증
   ├──────────────────────┐
   │ 허용•수정•차단•이관 │
   └──────────┬───────────┘
   │ 4. 정책 판정 집행
   ▼
도구
   │ 실행 결과•오류 반환
   ▼
에이전트
   │ 5. 출력 정책 검사
   │ 안전 응답
   ▼
사용자
```

### 동작 원리

1. **입력 위험•민감정보 검사**: 악성 지시•난독화 탐지
2. **신뢰 지시•비신뢰 문맥 분리**: 외부 문맥의 명령권 제거
3. **도구 인자•권한•부작용 검증**: 행동 위험 판정
4. **정책 판정 집행**: 격리•차단 또는 사람 이관 결정
5. **출력 정책 검사**: 유해성•민감정보 재검사

#### 한줄 요약

- **행동 위험** 검증 후 차단 또는 HITL 이관

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정책 엔진(Policy Engine)**: 선언된 역할•속성•규칙을 평가하여 자원과 행동의 접근 권한을 결정적으로 판정하는 구성요소.

</details>

| 통제 체계 | 에이전트 가드레일 | 정책 엔진 |
|:---|:---|:---|
| 적용 기준 | 의미 기반 동적 행동 위험 평가 | 결정적 접근 권한 평가 |
| 핵심 특징 | 규칙•분류기•사람의 다층 판정 | 선언 정책•속성의 허용 판정 |
| 한계 | 오탐•우회 공격 가능성 존재 | 정책 누락•속성 오류 존재 |

#### 한줄 요약

- 권한은 **정책 엔진**, 의미•행동 위험은 **가드레일**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오탐(False Positive)**: 정상 요청을 위험하다고 잘못 판정하여 허용해야 할 업무를 차단하는 오류.
- **미탐(False Negative)**: 위험 요청을 정상으로 잘못 판정하여 공격이나 정책 위반을 통과시키는 오류이다.
- **우회율(Bypass Rate)**: 공격 세트 가운데 가드레일을 피해 실제 실행 단계까지 도달한 비율.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 필터 우회에 따른 통제 실패 | **심층 방어** 기반 입력•문맥•도구•출력 독립 통제를 적용함 | 우회 공격 다층 차단을 수행함 |
| 과도한 차단에 따른 업무 저해 | **위험 기반 대응** 적용함 | 안전성과 업무 가용성 균형을 달성함 |
| 모델 판정만 신뢰한 권한 오용 | **도구 정책 집행기** 주체•대상•인자를 재검증함 | 생성 판단과 권한 집행을 분리함 |
| 정책 변경의 검출 성능 저하 | **오탐**•**미탐**•**우회율** 지속 평가함 | 가드레일 운영 임계치를 보정함 |

#### 한줄 요약

- 메일 발송 전 **수신자•첨부 민감정보** 재검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **최소 권한(Least Privilege)**: 가드레일이 판단을 놓쳐도 피해가 제한되도록 도구의 자원•행동 범위를 최소화하는 원칙으로 정의된다.

</details>

- 자율 AI 에이전트의 강력한 실행력과 보안 안전성 사이의 균형을 유지하는 **심층 방어 기반 에이전트 보안 거버넌스(Agent Guardrail / Input & Output Filter / Indirect Injection Defense / Tool Policy Enforcement & Tripwire / HITL)의 필수 보호 체계**로 확고히 자리 잡았으며, Llama Guard, NeMo Guardrails 등 특화 안전 모델 및 런타임 가드레일 프레임워크로 표준화되는 가운데, 실무 가드레일 시스템 설계 시에는 **입력·런타임·도구·출력의 4계층 독립 방어선 구축, 외부 데이터에 포함된 명령 실행을 원천 차단하는 지시-데이터 격리(Data Tagging/Delimiters) 기법 적용, 오탐(False Positive)으로 인한 업무 마비를 방지하기 위한 위험 기반 차등 대응(허용·마스킹·차단·HITL 이관) 정책 및 주기적 레드티밍(Red Teaming)**을 결합하여 완벽한 서비스 가용성과 시스템 방어력을 완성

#### 한줄 요약

- **피해 영향•가역성** 대상 따라 차단•승인 수준 결정
