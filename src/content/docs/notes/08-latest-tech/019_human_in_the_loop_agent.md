## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **인간 개입(Human-in-the-Loop, HITL)**: 에이전트 실행 과정에 사람의 검토•수정•승인 결정을 포함하는 통제 방식이다.
- **비가역 행동(Irreversible Action)**: 실행 뒤 원상 복구가 어렵거나 피해를 완전히 회수할 수 없는 행동.

</details>

- 정의: 사람이 계속•수정•거부•중단을 결정하는 **HITL** 통제
- 배경/필요성: AI 에이전트가 환각(Hallucination), 비인가 프롬프트 주입 또는 예기치 못한 비즈니스 예외 상황에서 자율적으로 판단하여 데이터 영구 삭제, 거액 송금, 대량 이메일 발송 등 비가역적(Irreversible) 고위험 행동을 수행할 경우 사후 복구가 불가능한 막대한 경영·재무적 피해가 발생함에 따라, 위험 등급과 불확실성을 사전 평가하여 고위험 실행 직전에 사람의 검토·수정·승인을 강제하는 인간 개입(HITL: Human-in-the-Loop) 제어 체계를 구축하여 **비가역 행동에 대한 사전 실행 중단(Interrupt) 및 상태 보존(Checkpoint), 승인 대기 중 상태 변경을 방어하는 실행 직전 상태 재검증(State Re-validation), 인간과 AI 간의 안전한 권한 공유 모델 확립**을 달성할 필요

#### 한줄 요약
- **비가역 행동**에만 사람을 끼워 넣는 것은 복구 불가 비용을 검토 지연 비용으로 바꾸는 거래이므로, 승인 지점을 늘릴수록 안전하되 지나치면 사람이 형식적으로 승인해 통제가 무력해진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **개입 조건(Intervention Condition)**: 위험도•불확실성•가역성을 평가하여 사람의 검토가 필요한 시점을 정한 기준이다.
- **검토 문맥(Review Context)**: 승인자가 실질적으로 판단할 수 있도록 제시하는 근거•예상 영향•대안•불확실성 정보.

</details>

- **개입 조건**: 위험 등급으로 승인•검토 시점 결정
- **검토 문맥**: 근거•영향•대안•불확실성 제공
- **상태 재검증**: 승인 후 최신 대상•권한 확인

#### 한줄 요약
- **검토 문맥** 기반 실질적 승인 판단 지원

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **중단(Interrupt)**: 부작용이 발생하기 전에 에이전트 실행을 안전하게 일시 정지하는 기능이다.
- **체크포인트(Checkpoint)**: 승인이나 예외 처리 뒤 재개할 수 있도록 중단 시점의 상태를 저장한 지점이다.
- **승인 관문(Approval Gate)**: 고위험 단계에서 사람의 승인•수정•거부 결정을 요구하는 통제 지점.
- **에스컬레이션(Escalation)**: 정해진 시간이나 권한으로 처리할 수 없는 예외를 상위 담당자에게 넘기는 절차.

</details>

```text
                       [위험 평가기]
                            |
                       [중단 계층]
                            |
                       [검토 계층]
                            |
                       [결정 라우터]
                            |
                       [정책 관리]
```

| 구성요소 | 책임 |
|:---|:---|
| 위험 평가기 | 영향•불확실성에 따른 **개입 조건** 판정 |
| 중단 계층 | **중단•체크포인트** 기반 부작용 차단 |
| 검토 계층 | **승인 관문**에서 근거•대안 표시 |
| 결정 라우터 | 승인•수정•거부의 상태 전이 관리 |
| 정책 관리 | **에스컬레이션**과 감사 기록 관리 |

#### 한줄 요약
- **위험 평가•중단**과 승인•결정 라우팅 기반 개입 통제

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 재검증(State Re-validation)**: 승인 대기 중 바뀔 수 있는 대상•금액•권한•정책을 실제 실행 직전에 다시 확인하는 절차이다.
- **승인 범위(Approval Scope)**: 사람이 허용한 대상•행동•조건의 경계로, 에이전트가 실행할 수 있는 범위.
- **영향•불확실성 평가(Impact/Uncertainty Evaluation)**: 예상 피해 규모와 결과 신뢰도를 분석해 인간 개입 조건을 판정하는 절차이다.
- **실행 중단•상태 저장(Execution Interrupt/State Save)**: 승인 전에 실행을 멈추고 이후 재개할 수 있도록 현재 상태를 보존하는 절차로 정의된다.
- **승인 결정 반영•최신 조건 재검증(Approval Reflection/Condition Re-validation)**: 사람의 결정을 적용하고 실행 직전 대상•권한•정책을 다시 확인하는 절차이다.
- **검증된 행동 실행(Verified Action Execution)**: 최신 상태에서도 유효한 승인 범위 안의 행동만 수행하는 절차로 정의된다.

</details>

```text
에이전트
   │ 1. 영향•불확실성 평가
   ▼
통제 엔진
   │ 2. 실행 중단•상태 저장
   │ 근거•영향•대안 검토 요청
   ▼
승인자
   │ 승인•수정•거부 결정
   ▼
통제 엔진
   │ 3. 승인 결정 반영•최신 조건 재검증
   │ 4. 검증된 행동 실행
   ▼
실행 대상
   │ 실행 결과•오류 반환
   ▼
에이전트
```

### 동작 원리

1. 영향•불확실성 평가: 피해 규모와 신뢰도에 따른 **개입 조건** 판정
2. 실행 중단•상태 저장: 승인 전 부작용 차단과 **체크포인트** 보존
3. 승인 결정 반영•최신 조건 재검증: **상태 재검증**으로 대상•권한 확인
4. 검증된 행동 실행: **승인 범위** 안의 행동만 수행

#### 한줄 요약
- 승인 후 **상태 재검증**을 거쳐 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인간 감시(Human-on-the-Loop)**: 정책에 따라 자동 실행하되 사람이 과정을 감시하고 필요할 때 중단•수정하는 통제 방식.
- **자동 실행(Autonomous Execution)**: 저위험 반복 행동을 정책 판정 뒤 별도 인간 승인 없이 즉시 수행하는 방식이다.
- **자동화 편향(Automation Bias)**: 사람이 자동화 시스템의 제안이나 결과를 충분히 검토하지 않고 옳다고 받아들이는 편향.

</details>

- **HITL•인간 감시•자동 실행** 개입 시점으로 구분

| 구분 | HITL | 인간 감시 | 자동 실행 |
|:---|:---|:---|:---|
| 적용 기준 | 고위험•**비가역 행동** | 가역적 감시 가능 행동 | 저위험•반복 행동 |
| 핵심 특징 | 인간 결정 후 조건부 실행 | 자동 실행 후 **인간 감시** | 정책 통과 후 **자동 실행** |
| 한계 | 승인 병목•**자동화 편향** 위험 | 개입 지연•감시 피로 발생 | 권한 남용•피해 확산 우려 |

> 요약: 사전 승인은 **HITL**, 실행 중 감시는 **인간 감시** 적용

#### 한줄 요약
- **행동 위험도**에 따라 사전 승인•실행 중 감시 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **위험 등급화(Risk Grading)**: 영향 규모•불확실성•가역성을 기준으로 행동을 분류하여 승인 수준과 응답 기한을 다르게 정하는 방식.
- **승인 병목(Approval Bottleneck)**: 검토 요청이 승인자의 처리 능력을 넘어 자동화 전체가 지연되는 현상.
- **거부 기본값(Default Deny)**: 승인 기한이 지나거나 담당자가 응답하지 않으면 행동을 자동으로 실행하지 않도록 정한 안전 상태.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모든 작업 승인에 따른 **승인 병목** | **위험 등급화** 기반 승인 수준 차등화 | 고위험 지점에 검토 역량 집중 |
| 근거 없는 승인에 따른 **자동화 편향** | **검토 문맥**에 근거•대안•영향 표시 | 실질적인 오류 발견 지원 |
| 승인 대기 중 대상 상태 변경 | 실행 직전 **상태 재검증** | 오래된 승인에 따른 오실행 방지 |
| 기한 초과 시 책임 공백 | 승인자•대체자•기한•**거부 기본값** 명시 | 예외 상황의 결정 책임 확보 |

#### 한줄 요약
- **위험 등급화** 기반 발송•결제 승인 수준•기한 차등화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **개입 시점 구분(Intervention Timing Division)**: 비가역•고위험 행동에는 HITL을 적용하고, 가역•감시 가능 행동에는 인간 감시를 적용해 통제 비용을 행동 위험도에 맞추는 결정으로 정의된다.

</details>

- 완전 자율 실행의 위험성을 인간의 비판적 판단력으로 안전하게 통제하는 **인간-AI 협업 및 안전 제어 아키텍처(Human-in-the-Loop Agent / Approval Gates & Checkpoint State / Risk Grading & Review Context / State Re-validation & Default Deny)의 필수 거버넌스 모델**로 확고히 자리 잡았으며, 인간 참여(HITL)에서 인간 감시(HOTL)로 점진적 자율성을 확대하는 적응형 에이전트 시스템으로 발전하는 가운데, 실무 HITL 아키텍처 구현 시에는 **비즈니스 영향도와 가역성에 기반한 정밀한 위험 등급화(Risk Grading) 및 차등 승인 워크플로 설계, 승인자의 형식적 승인(Automation Bias)을 방지하기 위한 풍부한 판단 근거(Review Context) 제공, 승인 지연 중 데이터 변조를 차단하는 실행 직전 2차 상태 재검증(State Re-validation) 및 타임아웃 시 거부 기본값(Default Deny) 정책 적용**을 결합하여 완벽한 비즈니스 안전성과 업무 생산성을 완성

#### 한줄 요약
- **비가역성•감시 가능성**에 따라 인간 개입 시점 결정
