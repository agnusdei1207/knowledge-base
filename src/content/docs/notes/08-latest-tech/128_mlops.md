## 미리 알고가기

- **머신러닝 운영(Machine Learning Operations, MLOps)**: '엠엘옵스'로 읽고 데이터·코드·모델의 학습·배포·운영을 연결하는 체계를 표시
- **지속적 통합(Continuous Integration, CI)**: '시아이'로 읽고 코드·데이터·파이프라인 변경을 자동 검증하는 통합
- **지속적 제공(Continuous Delivery, CD)**: '시디'로 읽고 검증·승인 모델을 단계적으로 전달하는 배포
- **지속적 학습(Continuous Training, CT)**: '시티'로 읽고 데이터·성능 변화에 따라 후보 모델을 재학습하는 과정

## Ⅰ. 개요

- 정의/개념: ML의 데이터·코드·학습·모델·배포·관측을 **재현 가능한 자동화 수명주기로 연결**
- **배경/필요성**: DevOps만으로 관리하기 어려운 **데이터·모델 버전·드리프트·재학습 운영 보완**

### 쉽게 이해하기 (학습용)

- 코드·데이터·모델을 같은 이력과 자동화 공정으로 연결해 검증된 모델만 운영한다.

## Ⅱ. 특징

- **코드·데이터·특징·실행·모델 계보**로 학습 결과를 재현·복구한다.
- **CI·CT·CD와 모델 레지스트리·승격 게이트**로 검증된 모델만 배포한다.
- **데이터·개념 드리프트·서비스 성능 관측**을 재학습·롤백 판단에 연결한다.

### 쉽게 이해하기 (학습용)

- 코드·데이터·모델 버전을 한 계보에 묶고 검사·배포·재학습을 자동으로 이어가는 방식이다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 파이프라인 | 검증·변환된 피처 공급 |
| 파이프라인 오케스트레이터 | 작업·의존 관계 관리 |
| 메타데이터 저장소 | 코드·데이터·실행 계보 기록 |
| 모델 레지스트리 | 모델 버전·평가·승격 상태 보관 |
| 서빙·모니터링 플랫폼 | 서빙·데이터·품질 변화 추적 |

> 요약: 파이프라인·계보·레지스트리·서빙을 연결한다

### 쉽게 이해하기 (학습용)

- 데이터 파이프라인·오케스트레이터·계보·레지스트리·모니터링을 연결해 모델 생성 과정을 추적한다.

## Ⅳ. 원리 및 절차 흐름도

```text
변경 접수 → CI 검증 → CT 학습·평가 → 등록·승격 → CD 배포
                                                ↓
                                            운영 관측
                                                ↓
                                            재학습 판정
                                  ├─ 충족 → CT로 복귀
                                  └─ 미충족 → 유지
```

| 절차 | 설명 |
|:---|:---|
| 변경 접수 | 코드·데이터·설정 변경 등록 |
| CI 검증 | 코드·스키마·파이프라인 검증 |
| CT 학습·평가 | 후보 모델 학습·성능 평가 |
| 등록·승격 | 통과 모델의 계보·상태 등록 |
| CD 배포 | 호환성 검증 뒤 단계 배포 |
| 운영 관측 | 데이터·품질·지연 변화 측정 |
| 재학습 판정 | 임계값 충족 시 CT 실행 |

> 요약: 변경을 검증·학습·배포하고 품질 저하에 재학습한다

### 쉽게 이해하기 (학습용)

- 새 코드·데이터를 검사해 후보를 만들고 검증된 모델만 배포하며 운영 품질이 떨어지면 다시 학습한다.

## Ⅴ. 종류 및 비교

| AI 운영 수명주기 | MLOps | DevOps | LLMOps |
|:---|:---|:---|:---|
| 적용 기준 | 예측 ML·드리프트 관리 | 앱 빌드·배포 자동화 | LLM 품질·안전·비용 관리 |
| 핵심 특징 | 데이터·모델 재학습 | 코드·인프라 배포 | 프롬프트·검색·응답 평가 |
| 한계 | 계보·드리프트 누락 | 모델·데이터 변화 미관리 | 생성 평가 변동성·비용 |

> 요약: MLOps·DevOps·LLMOps는 대상이 다르다.

### 쉽게 이해하기 (학습용)

- DevOps는 코드 배포, MLOps는 데이터 기반 재학습, LLMOps는 프롬프트·검색·생성 평가까지 관리한다.

## Ⅵ. 실무 사례

1. 이상거래 후보 모델을 **검증 게이트 후 카나리 배포**한다

### 쉽게 이해하기 (학습용)

- 데이터와 모델 기준을 통과한 버전만 일부 트래픽에서 기존 모델과 비교한다

## Ⅶ. 결론

- 모델의 재현 가능한 개발과 안전한 운영을 위해 **데이터·모델 계보·평가 게이트·승격·모니터링·재학습 조건**을 검토하고, 검증된 버전만 MLOps 파이프라인으로 배포한다

### 쉽게 이해하기 (학습용)

- 모델 생성 계보를 기록하고 검증된 모델만 배포하며 품질이 떨어질 때 재학습하는 체계가 핵심이다.
