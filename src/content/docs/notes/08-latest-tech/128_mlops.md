## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **기계학습 운영(Machine Learning Operations, MLOps)**: 데이터•코드•모델의 학습•배포•운영을 재현 가능한 자동화 수명주기로 연결하는 체계이다.
- **모델 계보**: 모델을 만든 코드•데이터•특징•실행 환경과 평가•배포 이력을 추적하는 기록이다.
- **기계학습(Machine Learning, ML)**: 데이터에서 패턴을 학습해 예측•분류를 수행하는 기술이다.
- **개발•운영(Development and Operations, DevOps)**: 코드와 인프라의 빌드•시험•배포를 자동화하는 운영체계이다.
- **인공지능(Artificial Intelligence, AI)**: 입력을 바탕으로 예측•생성•의사결정을 수행하는 시스템이다.

</details>

- 정의/개념: ML의 데이터•코드•학습•모델•배포•관측을 연결하는 **MLOps 체계**이다.
- 배경/필요성: DevOps의 **데이터•모델 계보•재학습 관리 한계**가 발생한다.

#### 한줄 요약

- 코드•데이터•모델을 같은 이력과 자동화 공정으로 연결해 검증된 모델만 운영한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **지속적 통합(Continuous Integration, CI)**: 코드•데이터•파이프라인 변경을 자동으로 통합하고 검증하는 과정이다.
- **지속적 학습(Continuous Training, CT)**: 데이터와 성능 변화에 따라 후보 모델을 자동으로 재학습하는 과정이다.
- **지속적 전달(Continuous Delivery, CD)**: 검증•승인된 모델을 단계적으로 배포 가능한 상태로 전달하는 과정이다.

</details>

- 학습 결과를 재현•복구하는 **코드•데이터•모델 계보**가 핵심이다.
- 검증된 모델만 배포하는 **CI•CT•CD•승격 게이트**가 핵심이다.
- 재학습•롤백을 정하는 **드리프트•서비스 성능 관측**이 핵심이다.

#### 한줄 요약

- 코드•데이터•모델 버전을 한 계보에 묶고 검사•배포•재학습을 자동으로 이어가는 방식이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **파이프라인 오케스트레이터**: 학습 작업의 순서•의존 관계•재시도와 실행 상태를 관리하는 구성요소이다.
- **데이터 파이프라인**: 원천 데이터를 검증•변환하여 학습과 추론에 일관된 특징을 공급하는 구성요소이다.
- **메타데이터 저장소**: 코드•데이터•특징•실행 환경과 결과의 계보를 기록하는 구성요소이다.
- **모델 레지스트리**: 모델 버전•평가 결과•승인과 승격 상태를 보관하는 개념이다.
- **서빙•모니터링 플랫폼**: 승인 모델을 배포하고 예측 품질•지연•데이터 변화를 관측해 재학습 판단에 제공하는 개념이다.

</details>

```text
                    [파이프라인 오케스트레이터]
                     /          |          \
          [데이터 파이프라인] [메타데이터 저장소] [모델 레지스트리]
                     \          |          /
                    [서빙•모니터링 플랫폼]
```
선의 의미: 파이프라인 오케스트레이터는 데이터 파이프라인, 메타데이터 저장소, 모델 레지스트리의 작업•계보•버전 경계를 통제하고, 서빙•모니터링 플랫폼은 세 영역의 운영 상태를 함께 관측한다.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 파이프라인 | 검증•변환된 피처 공급 |
| 파이프라인 오케스트레이터 | 작업•의존 관계 관리 |
| 메타데이터 저장소 | 코드•데이터•실행 계보 기록 |
| 모델 레지스트리 | 모델 버전•평가•승격 상태 보관 |
| 서빙•모니터링 플랫폼 | 서빙•데이터•품질 변화 추적 |

#### 한줄 요약

- 데이터 파이프라인•오케스트레이터•계보•레지스트리•모니터링을 연결해 모델 생성 과정을 추적한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **승격 게이트**: 평가 기준을 통과한 후보 모델만 다음 배포 단계로 이동시키는 승인 경계이다.
- **드리프트 신호**: 운영 데이터나 개념•성능 분포가 기준에서 달라졌음을 나타내는 지표이다.

</details>

```text
┌──────────── 모델 운영 종료까지 ────────────┐
│ 데이터 파이프라인 ── 1. 검증 데이터•변경 정보 ──▶ 오케스트레이터
│ 오케스트레이터 ── 2. CI•CT 실행 계보 ──▶ 메타데이터 저장소
│ 메타데이터 저장소 ── 3. 후보 모델•평가 결과 ──▶ 모델 레지스트리
│ 모델 레지스트리 ── 4. 승인 버전•CD 배포 ──▶ 서빙•모니터링 플랫폼
│ 오케스트레이터 ◀─ 5. 드리프트•재학습 신호 ── 서빙•모니터링 플랫폼
└─────────────────────────────────────────────┘
```

1. **검증 데이터•변경 정보**: 코드•스키마•특징 변경을 입력한다.
2. **CI•CT 실행 계보**: 파이프라인 검증과 후보 학습을 재현한다.
3. **후보 모델•평가 결과**: 모델 버전과 승격 근거를 연결한다.
4. **승인 버전•CD 배포**: 검증 통과 모델만 단계를 배포한다.
5. **드리프트•재학습 신호**: 운영 품질 변화로 CT 재실행을 판정한다.

#### 한줄 요약

- 새 코드•데이터를 검사해 후보를 만들고 검증된 모델만 배포하며 운영 품질이 떨어지면 다시 학습한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **DevOps 적용**: 애플리케이션 코드와 인프라의 배포를 자동화하는 방식이다.
- **거대 언어 모델 운영(Large Language Model Operations, LLMOps)**: 프롬프트•검색•모델•도구의 생성 응답을 품질•안전•비용 기준으로 운영하는 체계이다.

</details>

AI 운영은 MLOps, DevOps, LLMOps의 관리 대상을 구분한다.

| AI 운영 수명주기 | MLOps | DevOps | LLMOps |
|:---|:---|:---|:---|
| 적용 기준 | 예측 ML•**드리프트 관리** | 앱 **빌드•배포 자동화** | LLM **품질•안전•비용** 관리 |
| 핵심 특징 | 데이터•모델 **재학습** | 코드•인프라 **배포** | 프롬프트•검색•**응답 평가** |
| 한계 | 계보•**드리프트 누락** | 모델•데이터 **변화 미관리** | 생성 평가의 **변동성•비용** |

#### 한줄 요약

- DevOps는 코드 배포, MLOps는 데이터 기반 재학습, LLMOps는 프롬프트•검색•생성 평가까지 관리한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **재현 불가**: 코드•데이터•특징•환경 버전이 연결되지 않아 같은 모델을 다시 만들지 못하는 문제이다.
- **미검증 모델 승격**: 평가와 승인 상태를 거치지 않은 후보가 운영 환경에 배포되는 문제이다.
- **불필요한 자동 재학습**: 실제 드리프트 원인과 품질 영향을 확인하지 않고 CT를 실행해 회귀를 만드는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 학습 결과의 **재현 불가** | 코드•데이터•특징•실행의 **계보 연결** | 모델 **재생성•복구** |
| **미검증 모델 승격** | 평가 게이트•**레지스트리 상태** 적용 | **배포 품질 보존** |
| **불필요한 자동 재학습** | 데이터•개념 드리프트의 **CT 조건 설정** | **학습•회귀 방지** |

#### 한줄 요약

- 데이터와 모델 기준을 통과한 버전만 일부 트래픽에서 기존 모델과 비교한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **드리프트 임계치**: 데이터•개념•성능 변화가 재평가나 재학습을 시작할 수준인지 판정하는 기준이다.
- **단계 배포**: 승인 모델을 일부 트래픽부터 순차 확대하며 기존 모델과 성능을 비교하는 방식이다.

</details>

- **MLOps 계보•승격 통제**를 적용하고 드리프트 임계치 충족 시 재학습이 핵심이다.

#### 한줄 요약

- 모델 생성 계보를 기록하고 검증된 모델만 배포하며 품질이 떨어질 때 재학습하는 체계가 핵심이다.
