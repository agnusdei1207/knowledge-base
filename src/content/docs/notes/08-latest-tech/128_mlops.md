## 미리 알고가기

- **MLOps(Machine Learning Operations)**: 데이터·코드·모델의 학습·배포·운영을 연결하는 체계
- **CI(Continuous Integration)**: 코드·데이터·파이프라인 변경을 지속 검증하는 통합
- **CD(Continuous Delivery)**: 검증·승인된 모델을 운영 환경에 단계적으로 전달하는 배포
- **CT(Continuous Training)**: 데이터·성능 변화에 따라 후보 모델을 다시 학습하는 과정

## Ⅰ. 개요

- **정의/개념**: ML 개발·학습·배포·관측을 연결하는 운영 체계다
- **배경/필요성**: 데이터 변화와 환경 차이의 품질 저하를 막는다

### 쉽게 이해하기 (학습용)

- 코드·데이터·모델을 같은 이력과 자동화 공정으로 연결해 검증된 모델만 운영한다.

## Ⅱ. 특징

- 코드·데이터·모델 계보는 재현·복구 시간을 줄인다
- CI·CT·CD 연결은 검증 없는 모델 배포를 막는다
- 운영 관측은 드리프트와 품질 저하를 재학습에 잇는다
- 단계 배포·롤백은 새 모델의 서비스 피해를 줄인다
- 자동화된 증거는 승인·감사 책임의 공백을 막는다

### 쉽게 이해하기 (학습용)

- 코드·데이터·모델 버전을 한 계보에 묶고 검사·배포·재학습을 자동으로 이어가는 방식이다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 파이프라인 | 검증·변환된 피처 공급 |
| 파이프라인 오케스트레이터 | 작업·의존 관계 관리 |
| 메타데이터 저장소 | 코드·데이터·실행 계보 기록 |
| 모델 레지스트리 | 모델 버전·평가·승격 상태 보관 |
| 서빙·모니터링 플랫폼 | 서빙·데이터·품질 변화 추적 |

> 요약: 파이프라인·계보·레지스트리·서빙을 연결한다

### 쉽게 이해하기 (학습용)

- 데이터 파이프라인·오케스트레이터·계보·레지스트리·모니터링을 연결해 모델 생성 과정을 추적한다.

## Ⅳ. 원리 및 절차 흐름도

```text
변경 → CI 검증 → CT 학습·평가 → 등록·승격 → CD 배포
                                                ↓
                                            운영 관측
                                                ↓
                                            재학습 판정
                                  ├─ 충족 → CT로 복귀
                                  └─ 미충족 → 유지
```

| 절차 | 설명 |
|:---|:---|
| CI 검증 | 코드·스키마·파이프라인 검증 |
| CT 학습·평가 | 후보 모델 학습·성능 평가 |
| 등록·승격 | 통과 모델의 계보·상태 등록 |
| CD 배포 | 호환성 검증 뒤 단계 배포 |
| 운영 관측 | 데이터·품질 저하 시 CT 실행 |

> 요약: 변경을 검증·학습·배포하고 품질 저하에 재학습한다

### 쉽게 이해하기 (학습용)

- 새 코드·데이터를 검사해 후보를 만들고 검증된 모델만 배포하며 운영 품질이 떨어지면 다시 학습한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | MLOps | DevOps | 언어모델 운영 (LLMOps) |
|:---|:---|:---|:---|
| 핵심 특징 | 데이터 기반 재학습 | 코드·인프라 배포 | 생성 응답·검색 평가 |
| 적용 기준 | 예측 ML·드리프트 관리 | 앱 빌드·배포 자동화 | LLM 품질·안전·비용 관리 |
| 주요 위험 | 데이터 계보 누락 | 운영 데이터 변화 누락 | 생성 평가 변동성 |

> 요약: MLOps·DevOps·LLMOps는 대상이 다르다.

### 쉽게 이해하기 (학습용)

- DevOps는 코드 배포, MLOps는 데이터 기반 재학습, LLMOps는 프롬프트·검색·생성 평가까지 관리한다.

## Ⅵ. 실무 사례

1. 이상거래 후보 모델을 검증해 카나리 배포한다
2. 추천 데이터 변화가 임계값을 넘으면 CT를 실행한다

### 쉽게 이해하기 (학습용)

- 이상거래 후보는 기준 모델보다 나은지 검증한 뒤 일부 요청에 배포하고 저하되면 되돌린다.
- 추천 데이터 분포가 바뀌면 CT를 실행하고 새 모델의 온라인 성능을 확인한 뒤 승격한다.

## Ⅶ. 결론

- 모델 계보와 검증·승격·롤백을 한 흐름으로 관리한다.

### 쉽게 이해하기 (학습용)

- 모델 생성 계보를 기록하고 검증된 모델만 배포하며 품질이 떨어질 때 재학습하는 체계가 핵심이다.
