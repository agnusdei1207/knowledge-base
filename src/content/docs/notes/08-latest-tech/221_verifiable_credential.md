## 미리 알고가기

- **DID(분산 식별자)**: 한 회사 계정에 묶이지 않고 사용자가 스스로 관리하는 온라인 신분증 주소임
- **VC(검증가능 자격증명)**: 대학·회사 같은 발행기관이 전자서명으로 진짜임을 보증한 디지털 졸업증명서나 재직증명서임
- **VP(검증가능 제시물)**: 보유자가 VC에서 필요한 정보만 골라 상대방에게 보여 주기 위해 만드는 제출용 증명 묶음임
- **선택적 공개(Selective Disclosure)**: 성인 여부만 확인할 때 생년월일 전체는 숨기듯 필요한 정보만 보여 주는 방법임
- **상태 목록(Status List)**: 분실·퇴사 등으로 증명서가 더는 유효하지 않은지 확인하는 공개 확인 목록임


## Ⅰ. 개요

- **정의/개념**: 발급자가 무결성을 보증한 디지털 자격증명
- **배경/필요성**: 보유자 중심의 상호운용·최소 공개 검증을 지원

### 쉽게 이해하기 (학습용)

- 발행기관의 디지털 도장이 찍힌 자격증을 지갑에 보관했다가, 회사의 목적에 맞춰 필요한 정보만 선택적으로 제출하는 방식

## Ⅱ. 특징

- 발급자·보유자·검증자가 신뢰 역할을 분리한다.
- VC·VP 분리가 발급 정보와 제출 범위를 나눈다.
- 스키마·증명·상태가 구조·무결성을 검증한다.
- 선택 공개가 불필요한 개인정보 노출을 줄인다.

### 쉽게 이해하기 (학습용)

- 원본 자격증명과 제출용 봉투를 나누고, 봉투에는 상대가 꼭 확인해야 할 내용만 담되 도장·유효기간·취소 여부도 함께 검사함

## Ⅲ. 아키텍처 및 구성요소

```text
[VC 구성요소]
Issuer ── VC ── Holder ── VP ── Verifier
  │              │               │
  └───── Schema/Status/Key ──────┘
```

| 설계 요소 | 설명 |
|:---|:---|
| Issuer | Subject 정보에 서명해 VC를 발급함 |
| Holder | VC를 보관하고 VP로 제시함 |
| Verifier | VP 유효성과 업무 정책을 검증함 |
| VC/VP | claim과 암호학적 proof를 포함함 |
| Status | 자격 정지·취소 여부를 제공함 |

> 요약: 발행자의 VC를 보유자가 VP로 제시·검증

### 쉽게 이해하기 (학습용)

- 학교는 자격증을 발행하고 사용자는 지갑에서 제출 봉투를 만들며 회사는 도장 목록과 취소 목록, 채용 규칙을 함께 확인함

## Ⅳ. 원리 및 절차 흐름도

```text
요청
 ↓
생성
 ↓
검증
 ↓
판단
```

| 절차 | 설명 |
|:---|:---|
| 요청 | 검증기관이 목적과 챌린지를 명시함 |
| 생성 | 사용자가 VC 선택 및 VP를 구성함 |
| 검증 | 전자서명·상태값·무결성을 확인함 |
| 판단 | 기관의 정책과 신뢰도를 평가함 |

> 요약: 검증기관은 암호학적 증명과 업무 정책을 모두 검증함

### 쉽게 이해하기 (학습용)

- 학교가 확인해 발행한 증명서를 안전히 보관했다가 요청 목적에 맞게 최소 정보로 제출하고, 회사가 기술 검사와 채용 판단을 차례로 수행함

## Ⅴ. 종류 및 비교

| 판단 기준 | 전자문서 증명서 | 중앙 API 조회 | Verifiable Credential |
|:---|:---|:---|:---|
| 핵심 특징 | 파일 단위 전자문서 제출 | 발행기관 서버에 실시간 조회 | 보유자가 VC를 VP로 직접 제시 |
| 적용 기준 | 단순 문서 전달·수작업 검토 | 최신 상태를 기관이 중앙 제공 | 상호운용·최소 공개 검증 |
| 주요 위험 | 과다 공개·format 종속 | 가용성·조회 추적·기관 종속 | 키 관리·상태 조회 상관관계 |

> 요약: 표준화된 자격증 제출 후 검증기관의 정책 판단이 필수임

### 쉽게 이해하기 (학습용)

- 파일 전체를 보내거나 학교 서버에 매번 묻는 대신 표준 증명서를 직접 제출하되, 회사는 도장이 진짜인지와 그 학교 자격을 인정할지를 모두 판단함

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 대학 학위 검증: 대학이 학위명·수여일·subject를 담은 VC를 졸업생 wallet에 발급하고 기업은 지원자가 만든 VP의 issuer proof·schema·status·holder binding을 확인한 뒤 해당 대학·학위를 채용 기준에서 인정할지 판단함
- 성인 여부 최소 공개: 공공기관이 생년월일 credential을 발급하고 이용자는 서비스별 challenge·audience에 묶인 VP로 ‘기준 연령 이상’만 공개하며, stable identifier와 status 조회가 여러 verifier의 이용 기록을 연결하지 않도록 unlinkable disclosure·proxy·cache를 설계함

## Ⅶ. 결론

- 발행자 신뢰·최소 공개·상태 검증으로 VC 채택 결정

### 쉽게 이해하기 (학습용)

- 디지털 도장이 진짜라는 사실과 자격 내용이 믿을 만하고 현재 업무에 적합하다는 판단은 다르므로 발행·보관·제출·검증 전 과정을 함께 관리해야 함
