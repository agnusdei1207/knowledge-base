## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 간 프로토콜(Agent2Agent Protocol, A2A)**: 서로 다른 에이전트가 능력을 발견하고 메시지•작업•결과물을 교환하는 상호운용 프로토콜.
- **이기종 협업(Heterogeneous Collaboration)**: 구현 방식이나 제공자가 다른 에이전트들이 표준 계약으로 함께 작업하는 방식이다.

</details>

- 정의: 원격 에이전트의 능력•상태형 작업•결과물을 교환하는 **A2A**
- 배경/필요성: 서로 다른 플랫폼, 벤더, 프레임워크(AutoGPT, CrewAI, LangGraph 등)로 개발된 이기종 AI 에이전트들이 복합 과업을 공동 수행할 때, 상호 간의 능력 탐색(Capability Discovery), 장기 실행 작업(Long-running Task)의 상태 동기화 및 산출물(Artifact) 교환 규격이 부재하여 시스템 간 직접 연동 비용이 기하급수적으로 증가하는 문제가 발생함에 따라, 에이전트의 능력과 보안 요구를 명시하는 에이전트 카드(Agent Card)와 상태형 작업(Stateful Task) 생명주기를 표준화한 에이전트 간 통신 프로토콜(A2A Protocol)을 정립하여 **이기종 다중 에이전트 간 표준 상호운용성 보장, 웹훅 및 스트리밍 기반의 비동기 장기 작업 상태 추적, 에이전트 내부 구조를 은닉하는 캡슐화(Encapsulation) 기반의 안전한 작업 위임 생태계 구축**을 달성할 필요

#### 한줄 요약

- **Agent Card•상태형 작업**은 상대의 내부 구현을 감춘 채 능력만 공시하므로, 세밀한 협조를 포기하는 대신 이기종 조합의 확장성을 택한 계약이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **캡슐화(Encapsulation)**: 에이전트 내부 모델•메모리•도구를 숨기고 외부 계약만 공개하는 설계 원칙.
- **에이전트 카드(Agent Card)**: 능력•기술•종단점•보안 요구를 공개하는 메타데이터.
- **푸시 알림(Push Notification)**: 장기 작업의 상태 변화를 등록된 웹훅으로 통지하는 방식.
- **A2A-Version**: 요청의 A2A 주•부 버전을 지정해 호환 의미를 고정하는 헤더.

</details>

- **캡슐화**: 내부 모델•메모리•도구 비공개
- **에이전트 카드**: 능력•종단점•인증 요구 공개
- **상태형 작업**: 스트리밍•푸시 알림 지원
- **A2A-Version**: JSON-RPC•gRPC•HTTP+JSON 호환

#### 한줄 요약

- **Agent Card•프로토콜 바인딩** 기반 능력 교환

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메시지(Message)**: 역할과 콘텐츠를 담은 단발 통신 단위.
- **작업(Task)**: 식별자와 진행 상태를 가진 장기 업무 단위로 정의된다.
- **결과물(Artifact)**: 작업이 생성한 문서•데이터 등의 산출물로 정의된다.
- **파트(Part)**: 메시지와 결과물을 이루는 텍스트•파일•데이터 콘텐츠 단위이다.

</details>

```text
                          [A2A 서버]
                    /        |        |        \
       [A2A 클라이언트] [에이전트 카드] [작업•메시지] [결과물]
```

선의 의미: A2A 서버가 카드•작업•결과물을 하나의 원격 경계로 제공하는 구조

| 구성요소 | 책임 |
|:---|:---|
| A2A 클라이언트 | 원격 에이전트 카드 조회와 작업 위임 |
| A2A 서버 | **메시지•작업** 및 결과물 처리 |
| 에이전트 카드 | **에이전트 카드**에 능력•종단점•인증 요구 게시 |
| 작업•메시지 | 단발 메시지와 상태형 작업 구분 |
| 결과물 | 작업 산출물을 **파트** 기반 전달 |

#### 한줄 요약

- **Agent Card•Task ID** 기반 능력•결과물 추적

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태형 작업(Stateful Task)**: 생성•진행•완료•실패 같은 상태를 식별자로 추적하는 장기 작업으로 정의된다.
- **스트리밍(Streaming)**: 작업 상태나 결과 일부를 완료 전부터 연속적으로 전달하는 방식으로 정의된다.
- **종결 상태(Terminal State)**: 작업이 완료•실패•취소되어 더 이상 진행되지 않는 상태.
- **작업 식별자(Task Identifier, Task ID)**: 장기 작업의 상태와 결과물을 일관되게 연결하는 고유 값이다.
- **버전•능력•인증 검증(Version/Capability/Authentication Validation)**: A2A-Version과 카드•요청 권한을 확인하는 단계.
- **상태형 작업 생성(Stateful Task Creation)**: Task ID와 초기 상태를 발급하는 단계.
- **작업 상태•결과물 갱신(Task State and Artifact Update)**: 상태 전이와 결과물 증분을 기록하는 단계.
- **스트리밍•푸시 상태 통지(Streaming/Push State Notification)**: 진행 상태를 구독 채널과 웹훅으로 전달하는 단계.
- **종결 결과물 확정•반환(Final Artifact Confirmation/Return)**: 종결 상태에서 Task ID와 최종 산출물을 연결하는 단계로 정의된다.

</details>

- **A2A Client**의 능력 확인 후 Task ID•결과물 추적

```text
A2A 클라이언트
   │ 에이전트 카드 조회
   ▼
A2A 서버
   │ 능력•인증 요구 반환
   ▼
A2A 클라이언트
   │ 메시지•작업 위임
   ▼
A2A 서버
   │ 1. 버전•능력•인증 검증
   │ 2. 상태형 작업 생성
   ▼
원격 에이전트 실행기
   ├──────────────────────┐
   │ 종결 상태 전까지     │
   └──────────┬───────────┘
   │ 3. 작업 상태•결과물 갱신
   ▼
A2A 서버
   │ 4. 스트리밍•푸시 상태 통지
   │ 5. 종결 결과물 확정
   │ 최종 결과물 반환
   ▼
A2A 클라이언트
```

### 동작 원리

1. 버전•능력•인증 검증: A2A-Version과 카드•요청 권한 확인
2. 상태형 작업 생성: Task ID와 초기 상태 발급
3. 작업 상태•결과물 갱신: 상태 전이•결과물 증분 기록
4. 스트리밍•푸시 상태 통지: **스트리밍•푸시 알림**으로 진행 상태 전달
5. 종결 결과물 확정: **종결 상태**에서 Task ID와 최종 산출물 연결

#### 한줄 요약

- **상태형 작업•Task ID** 기반 위임부터 완료까지 추적

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 모델에 외부 도구•리소스•프롬프트를 연결하는 프로토콜로 정의된다.
- **작업 위임(Task Delegation)**: 다른 에이전트에 목표를 전달하고 진행 상태와 결과를 받는 협업 방식.

</details>

- **A2A•MCP**를 원격 위임과 모델 기능 연결로 구분

| 프로토콜 | A2A | MCP |
|:---|:---|:---|
| 적용 기준 | **A2A** 기반 원격 에이전트 **작업 위임** | **MCP** 기반 모델 기능•데이터 연결 |
| 핵심 특징 | 능력•메시지•**상태형 작업** 제공 | 도구•리소스•프롬프트 연결 |
| 한계 | 상대 신뢰•작업 상태 관리 필요 | 서버별 권한•컨텍스트 통제 필요 |

> 요약: 에이전트 위임은 **A2A**, 모델 기능 연결은 **MCP** 적용

#### 한줄 요약

- 원격 작업 위임은 **A2A**, 모델 기능 연결은 **MCP**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 구간 암호화를 제공하는 프로토콜.
- **멱등키(Idempotency Key)**: 같은 요청이 반복돼도 작업을 한 번만 처리하도록 중복을 식별하는 키로 정의된다.
- **무결성(Integrity)**: 결과물이 생성 후 허가 없이 변경되지 않았음을 보장하는 성질이다.
- **에이전트 간 신뢰(Agent-to-Agent Trust)**: 카드 서명•TLS•작업 상태 추적으로 서로 다른 제공자의 에이전트가 작업을 위임•완료할 때 안전성을 확보하는 원칙.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위조 카드로 악성 에이전트 선택 | 카드 서명•**TLS**•발급 주체 검증 | 신원•능력 신뢰 확보 |
| 장기 작업의 상태 불일치 | **Task ID•멱등키** 기반 전이 관리 | 중복 실행•결과 혼선 방지 |
| 결과물 변조 | 해시•생성 주체로 **무결성** 검증 | 추적성•책임성 확보 |

#### 한줄 요약

- **카드•작업 상태**와 결과물 무결성 함께 검증

## Ⅶ. 결론

- 이기종 AI 에이전트들이 벤더와 프레임워크의 경계를 넘어 자율적으로 소통하고 협업할 수 있도록 지원하는 **에이전트 간 통신 및 작업 위임 프로토콜 표준(Agent to Agent Protocol: A2A / Agent Card & Capability Discovery / Stateful Task & Artifact / Streaming & Push Notification)의 차세대 인터페이스 표준**으로 확고히 자리 잡았으며, 도구 연결을 담당하는 MCP와 결합되어 'MCP(도구/리소스) + A2A(에이전트 협업)'의 완벽한 상호운용성 스택으로 진화하는 가운데, 실무 A2A 기반 분산 에이전트 시스템 구축 시에는 **에이전트의 능력과 엔드포인트 및 인증 방식을 기술한 Agent Card 서명 검증, 장기 비동기 작업의 중복 실행을 차단하는 Task ID 및 멱등성 키(Idempotency Key) 관리, 작업 결과물(Artifact)의 해시 기반 무결성 검증 및 TLS 암호화 통신**을 결합하여 완벽한 분산 에이전트 협업 신뢰성과 확장성을 완성

#### 한줄 요약

- 원격 상태 추적은 **A2A**, 모델 기능 연결은 **MCP** 선택
