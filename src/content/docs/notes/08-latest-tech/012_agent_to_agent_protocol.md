## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **에이전트 간 프로토콜(Agent2Agent Protocol, A2A)**: 서로 다른 에이전트가 능력을 발견하고 메시지•작업•결과물을 교환하는 상호운용 프로토콜이다.
- **이기종 협업**: 구현 방식이나 제공자가 다른 에이전트들이 표준 계약으로 함께 작업하는 방식이다.

</details>

- 정의/개념: 원격 에이전트의 능력과 인증 요구를 발견하고 상태형 작업과 결과물을 교환하는 **A2A**이다.
- 배경/필요성: 에이전트별 **능력 공개•작업 상태** 차이로 이기종 협업마다 개별 연동을 필요로 한다.

#### 한줄 요약

- 이기종 에이전트가 **능력 발견•상태형 작업**으로 협업이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **캡슐화**: 에이전트 내부 모델•메모리•도구를 숨기고 외부 계약만 공개하는 설계 원칙이다.
- **에이전트 카드(Agent Card)**: 능력•기술•종단점•보안 요구를 공개하는 메타데이터이다.
- **푸시 알림(Push Notification)**: 장기 작업의 상태 변화를 등록된 웹훅으로 통지하는 방식이다.
- **A2A-Version**: 요청의 A2A 주•부 버전을 지정해 호환 의미를 고정하는 헤더이다.

</details>

- **A2A** 구성은 클라이언트•서버•에이전트 카드•작업•메시지•결과물로 역할을 분리한다.

- **캡슐화 축**: 내부 모델•메모리•도구 비공개이다.
- **에이전트 카드**로 능력•인증 요구 공개가 핵심이다.
- **작업•메시지**와 스트리밍•**푸시 알림**을 지원한다.
- **A2A-Version**과 JSON-RPC•gRPC•HTTP+JSON 바인딩을 지원한다.

#### 한줄 요약

- **에이전트 카드•프로토콜 바인딩**으로 내부 구현 없이 위이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메시지(Message)**: 역할과 콘텐츠를 담은 단발 통신 단위이다.
- **작업(Task)**: 식별자와 진행 상태를 가진 장기 업무 단위이다.
- **결과물(Artifact)**: 작업이 생성한 문서•데이터 등의 산출물이다.
- **파트(Part)**: 메시지와 결과물을 이루는 텍스트•파일•데이터 콘텐츠 단위이다.

</details>

```text
                          [A2A 서버]
                    /        |        |        \
       [A2A 클라이언트] [에이전트 카드] [작업•메시지] [결과물]
```

선의 의미: A2A 서버는 클라이언트 접점, 능력과 인증 요구를 담은 에이전트 카드, 상태형 작업•메시지, 작업 산출물인 결과물을 하나의 원격 에이전트 경계로 제공한다.

| 구성요소 | 책임 |
|:---|:---|
| A2A 클라이언트 | 원격 에이전트의 **능력 발견•작업 위임** |
| A2A 서버 | **메시지•작업•결과물** 처리 |
| 에이전트 카드 | 능력•기술•종단점•**인증 요구** 게시 |
| 작업•메시지 | 단발 통신과 **상태형 작업** 구분 |
| 결과물 | 작업 산출물을 **결과물•파트**로 전달 |

#### 한줄 요약

- **에이전트 카드•Task ID**로 능력과 결과물을 추적한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **상태형 작업**: 생성•진행•완료•실패 같은 상태를 식별자로 추적하는 장기 작업이다.
- **스트리밍**: 작업 상태나 결과 일부를 완료 전부터 연속적으로 전달하는 방식이다.
- **종결 상태**: 작업이 완료•실패•취소되어 더 이상 진행되지 않는 상태이다.
- **작업 식별자(Task Identifier, Task ID)**: 장기 작업의 상태와 결과물을 일관되게 연결하는 고유 값이다.

</details>

- **A2A** 클라이언트가 능력을 확인한 뒤 작업을 위임하고 **Task ID•결과물**을 추적한다.

```text
A2A 클라이언트
   │ 에이전트 카드 조회
   ▼
A2A 서버
   │ 능력•인증 요구 반환
   ▼
A2A 클라이언트
   │ 메시지•작업 위임
   ▼
A2A 서버
   │ 1. 버전•능력•인증 검증
   │ 2. 상태형 작업 생성
   ▼
원격 에이전트 실행기
   ├──────────────────────┐
   │ 종결 상태 전까지     │
   └──────────┬───────────┘
   │ 3. 작업 상태•결과물 갱신
   ▼
A2A 서버
   │ 4. 스트리밍•푸시 상태 통지
   │ 5. 종결 결과물 확정•반환
   ▼
A2A 클라이언트
```

1. **버전•능력•인증 검증**: A2A-Version과 카드•요청 권한을 확인한다.
2. **상태형 작업 생성**: Task ID와 초기 상태를 발급한다.
3. **작업 상태•결과물 갱신**: 상태 전이•결과물 증분을 기록한다.
4. **스트리밍•푸시 상태 통지**: 진행 상태를 구독 채널로 전달한다.
5. **종결 결과물 확정•반환**: Task ID에 최종 산출물을 연결한다.

#### 한줄 요약

- **에이전트 카드•Task ID**로 작업 위임부터 완료까지 추적한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 모델에 외부 도구•리소스•프롬프트를 연결하는 프로토콜이다.
- **작업 위임**: 다른 에이전트에 목표를 전달하고 진행 상태와 결과를 받는 협업 방식이다.

</details>

- **A2A** 및 **MCP** 사이를 원격 작업 위임과 모델 기능 연결 기준으로 구분한다.

| 프로토콜 | A2A | MCP |
|:---|:---|:---|
| 적용 기준 | 원격 에이전트에 **작업 위임** | 모델에 **기능•데이터** 연결 |
| 핵심 특징 | 능력•메시지•**상태형 작업** | 도구•리소스•**프롬프트** |
| 한계 | **상대 신뢰•작업 상태 관리** | **서버별 권한•컨텍스트 통제** |

> 요약: 에이전트 작업 위임에는 **A2A**, 모델 기능 연결에는 **MCP**을 적용한다.

#### 한줄 요약

- 원격 작업 위임은 **A2A**, 모델 기능 연결은 **MCP**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 구간 암호화를 제공하는 프로토콜이다.
- **멱등키**: 같은 요청이 반복돼도 작업을 한 번만 처리하도록 중복을 식별하는 키이다.
- **무결성**: 결과물이 생성 후 허가 없이 변경되지 않았음을 보장하는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위조 카드로 **악성 에이전트 선택** | **카드 서명•TLS•발급 주체** 검증 | 신원•능력 신뢰 확보 |
| 장기 작업으로 **상태 불일치** | **Task ID•버전•멱등키** 기반 전이 관리 | 중복 실행•결과 혼선 방지 |
| 결과물 변조로 **출처•무결성 상실** | **해시•생성 주체•근거** 검증 | 추적성•책임성 확보 |

#### 한줄 요약

- **카드 신뢰•작업 상태•결과물 무결성**을 함께 검증한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **에이전트 간 신뢰**: 카드 서명•TLS•작업 상태 추적으로 서로 다른 제공자의 에이전트가 작업을 위임•완료할 때 안전성을 확보하는 원칙이다.

</details>

- 원격 에이전트 작업 위임에는 **A2A**, 모델 기능 연결에는 **MCP**을 선택한다.

#### 한줄 요약

- **카드 서명•결과물 무결성**을 확인한 뒤 작업 위이다.
