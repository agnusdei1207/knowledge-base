## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 간 프로토콜(Agent2Agent Protocol, A2A)**: 서로 다른 에이전트가 능력을 발견하고 메시지•작업•결과물을 교환하는 상호운용 프로토콜이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **이기종 협업(Heterogeneous Collaboration)**: 구현 방식이나 제공자가 다른 에이전트들이 표준 계약으로 함께 작업하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

- 정의/개념: 원격 능력•상태형 작업•결과물을 교환하는 **A2A**
- 배경/필요성: 이기종 에이전트는 **능력•작업 상태 계약 불일치**

#### 한줄 요약

- **Agent Card•상태형 작업**으로 능력•결과 교환

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **캡슐화(Encapsulation)**: 에이전트 내부 모델•메모리•도구를 숨기고 외부 계약만 공개하는 설계 원칙을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **에이전트 카드(Agent Card)**: 능력•기술•종단점•보안 요구를 공개하는 메타데이터이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **푸시 알림(Push Notification)**: 장기 작업의 상태 변화를 등록된 웹훅으로 통지하는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **A2A-Version**: 요청의 A2A 주•부 버전을 지정해 호환 의미를 고정하는 헤더를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- **캡슐화**: 내부 모델•메모리•도구 비공개
- **에이전트 카드**: 능력•종단점•인증 요구 공개
- **상태형 작업**: 스트리밍•푸시 알림 지원
- **A2A-Version**: JSON-RPC•gRPC•HTTP+JSON 호환

#### 한줄 요약

- **Agent Card•프로토콜 바인딩**으로 능력 교환

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메시지(Message)**: 역할과 콘텐츠를 담은 단발 통신 단위이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **작업(Task)**: 식별자와 진행 상태를 가진 장기 업무 단위로 정의된다.
- **결과물(Artifact)**: 작업이 생성한 문서•데이터 등의 산출물로 정의된다.
- **파트(Part)**: 메시지와 결과물을 이루는 텍스트•파일•데이터 콘텐츠 단위를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

```text
                          [A2A 서버]
                    /        |        |        \
       [A2A 클라이언트] [에이전트 카드] [작업•메시지] [결과물]
```

선의 의미: A2A 서버는 클라이언트 접점, 능력과 인증 요구를 담은 에이전트 카드, 상태형 작업•메시지, 작업 산출물인 결과물을 하나의 원격 에이전트 경계로 제공함.

| 구성요소 | 책임 |
|:---|:---|
| A2A 클라이언트 | 원격 에이전트 카드 조회와 작업 위임을 수행함 |
| A2A 서버 | **메시지**•**작업**•**결과물** 처리를 수행함 |
| 에이전트 카드 | **에이전트 카드**에 능력•기술•종단점•인증 요구를 게시함 |
| 작업•메시지 | 메시지와 상태를 가진 작업을 구분함 |
| 결과물 | 작업 산출물을 결과물과 **파트**로 전달함 |

#### 한줄 요약

- **Agent Card•Task ID**로 능력•결과물 추적

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태형 작업(Stateful Task)**: 생성•진행•완료•실패 같은 상태를 식별자로 추적하는 장기 작업으로 정의된다.
- **스트리밍(Streaming)**: 작업 상태나 결과 일부를 완료 전부터 연속적으로 전달하는 방식으로 정의된다.
- **종결 상태(Terminal State)**: 작업이 완료•실패•취소되어 더 이상 진행되지 않는 상태이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **작업 식별자(Task Identifier, Task ID)**: 장기 작업의 상태와 결과물을 일관되게 연결하는 고유 값을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **버전•능력•인증 검증(Version/Capability/Authentication Validation)**: A2A-Version과 카드•요청 권한을 확인하는 단계를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **상태형 작업 생성(Stateful Task Creation)**: Task ID와 초기 상태를 발급하는 단계를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **작업 상태•결과물 갱신(Task State and Artifact Update)**: 상태 전이와 결과물 증분을 기록하는 단계를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **스트리밍•푸시 상태 통지(Streaming/Push State Notification)**: 진행 상태를 구독 채널과 웹훅으로 전달하는 단계를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **종결 결과물 확정•반환(Final Artifact Confirmation/Return)**: 종결 상태에서 Task ID와 최종 산출물을 연결하는 단계로 정의된다.

</details>

- **A2A Client**가 능력 확인 후 Task ID•결과물 추적

```text
A2A 클라이언트
   │ 에이전트 카드 조회
   ▼
A2A 서버
   │ 능력•인증 요구 반환
   ▼
A2A 클라이언트
   │ 메시지•작업 위임
   ▼
A2A 서버
   │ 1. 버전•능력•인증 검증
   │ 2. 상태형 작업 생성
   ▼
원격 에이전트 실행기
   ├──────────────────────┐
   │ 종결 상태 전까지     │
   └──────────┬───────────┘
   │ 3. 작업 상태•결과물 갱신
   ▼
A2A 서버
   │ 4. 스트리밍•푸시 상태 통지
   │ 5. 종결 결과물 확정•반환
   ▼
A2A 클라이언트
```

### 동작 원리

1. **버전•능력•인증 검증**: A2A-Version과 카드•요청 권한을 확인함.
2. **상태형 작업 생성**: Task ID와 초기 상태를 발급함.
3. **작업 상태•결과물 갱신**: 상태 전이•결과물 증분을 기록함.
4. **스트리밍•푸시 상태 통지**: **스트리밍**과 **푸시 알림**으로 진행 상태를 전달함.
5. **종결 결과물 확정•반환**: **종결 상태**에서 Task ID에 최종 산출물을 연결함.

#### 한줄 요약

- **상태형 작업•Task ID**로 위임부터 완료까지 추적

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 모델에 외부 도구•리소스•프롬프트를 연결하는 프로토콜로 정의된다.
- **작업 위임(Task Delegation)**: 다른 에이전트에 목표를 전달하고 진행 상태와 결과를 받는 협업 방식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **A2A•MCP**를 원격 위임과 모델 기능 연결로 구분

| 프로토콜 | A2A | MCP |
|:---|:---|:---|
| 적용 기준 | **A2A**는 원격 에이전트에 **작업 위임**을 수행함 | **MCP**는 모델에 기능•데이터 연결을 수행함 |
| 핵심 특징 | 능력•메시지•**상태형 작업**을 제공함 | 도구•리소스•프롬프트 연결을 제공함 |
| 한계 | 상대 신뢰•작업 상태 관리가 필요함 | 서버별 권한•컨텍스트 통제가 필요함 |

> 요약: 에이전트 작업 위임에는 **A2A**, 모델 기능 연결에는 **MCP**를 적용함.

#### 한줄 요약

- 원격 작업 위임은 **A2A**, 모델 기능 연결은 **MCP**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 구간 암호화를 제공하는 프로토콜을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **멱등키(Idempotency Key)**: 같은 요청이 반복돼도 작업을 한 번만 처리하도록 중복을 식별하는 키로 정의된다.
- **무결성(Integrity)**: 결과물이 생성 후 허가 없이 변경되지 않았음을 보장하는 성질을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **에이전트 간 신뢰(Agent-to-Agent Trust)**: 카드 서명•TLS•작업 상태 추적으로 서로 다른 제공자의 에이전트가 작업을 위임•완료할 때 안전성을 확보하는 원칙이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위조 카드로 악성 에이전트 선택 | 카드 서명•**TLS**•발급 주체 검증을 수행함 | 신원•능력 신뢰를 확보함 |
| 장기 작업의 상태 불일치 | **Task ID**•버전•**멱등키** 기반 전이 관리를 적용함 | 중복 실행•결과 혼선을 방지함 |
| 결과물 변조 | 해시•생성 주체•근거로 **무결성**을 검증함 | 추적성•책임성을 확보함 |

#### 한줄 요약

- **카드•작업 상태•결과물 무결성**을 함께 검증

## Ⅶ. 결론

- 원격 작업 위임은 **A2A**, 모델 기능 연결은 **MCP** 선택

#### 한줄 요약

- **위임 대상•상태 추적 필요성**에 따라 A2A•MCP 결정
