## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 레지스트리(Model Registry)**: 학습이 완료된 다양한 머신러닝 모델의 버전, 하이퍼파라미터, 메타데이터 및 아티팩트를 체계적으로 저장하고 배포 라이프사이클을 추적/관리하는 중앙 저장소
- **평가 증적**: 특정 모델 버전이 품질•안전•성능 기준을 충족했음을 입증하는 시험 결과 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

- 정의/개념: 불변 버전•계보•평가•배포 상태의 **모델 레지스트리**
- 배경/필요성: 파일 저장만으로 **학습 출처•평가 증적•롤백 근거** 추적하기 어렵음.

#### 한줄 요약

- 계보•평가 결과를 기록하고 **승인 버전**만 배포 연결

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **불변 모델 버전**: 등록 뒤 내용이 바뀌지 않아 계보•평가•배포 결과를 같은 산출물에 연결하는 단위을  역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **배포 게이트**: 검증 상태와 승인 기록을 충족한 모델만 운영 단계로 이동시키는 경계 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **배포 별칭**: 운영•검증 같은 논리 이름을 승인된 특정 모델 버전에 연결하는 참조을  역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

- 불변 모델 버전과 **데이터•코드 계보**
- 검증 상태•승인 기록 기반 **배포 게이트**
- 배포 별칭 전환 기반 **승격**•**롤백**

#### 한줄 요약

- 버전별 모델에 계보와 검사 상태를 남기고 운영 별칭은 승인된 버전에만 붙인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 이름**: 관련 버전들을 하나의 제품이나 과업으로 묶는 고유 이름 공간 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **계보 정보**: 모델을 만든 데이터•코드•실험 실행과 환경을 산출물에 연결한 기록 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **승인 정책**: 모델 상태와 배포 별칭을 전환할 기준•권한•책임 주체를 정한 규칙 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

```text
                         [모델 이름]
                              |
                         [불변 버전]
                        /           \
                   [계보 정보]    [상태•별칭]
                                      |
                                  [승인 정책]
```
선의 의미: 모델 이름은 불변 버전의 이름 공간이고, 각 불변 버전은 계보 정보와 상태•별칭을 함께 보유하며, 승인 정책은 상태•별칭 변경의 권한 경계를 통제한다.

| 구성요소 | 책임 |
|:---|:---|
| 모델 이름 | 버전 묶음용 고유 이름 공간 |
| 불변 버전 | 배포 가능한 가중치 및 규격 단위 |
| 계보 정보 | 원본 실행 및 데이터 연결 정보 |
| 상태•별칭 | 검증 상태 및 배포 대상 관리 |
| 승인 정책 | 전환 조건 및 주체 관리 |

#### 한줄 요약

- 이름•버전•계보•상태•별칭의 **수명주기 구조**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **불변 해시**: 모델 산출물 내용이 바뀌지 않았음을 확인하는 고유 해시값 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **원자적 별칭 전환**: 운영 참조가 중간 상태 없이 한 승인 버전에서 다른 버전으로 한 번에 바뀌는 처리하는 개념을  역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

```text
실험 추적기
   │ 1. 산출물•계보 등록
   ▼
모델 레지스트리
   │ 2. 불변 해시•평가 증적 검증
   ▼
승인 정책
   │ 3. 승인•원자적 별칭 전환
   ▼
배포 시스템
   │ 4. 배포 버전•상태 동기화
   ▼
운영 감시
   └── 5. 운영 이상•롤백 판정 ──▶ 모델 레지스트리
```

### 동작 원리

1. **산출물•계보 등록**: 모델 해시와 데이터•코드•실험 실행을 연결함.
2. **불변 해시•평가 증적 검증**: 동일 산출물의 품질•안전을 심사함.
3. **승인•원자적 별칭 전환**: 검증 버전에만 운영 참조를 연결함.
4. **배포 버전•상태 동기화**: 서비스 모델과 레지스트리를 일치함.
5. **운영 이상•롤백 판정**: 이전 승인 버전으로 별칭을 복원함.

#### 한줄 요약

- 승인 시 별칭을 전환하고 이상 시 **이전 승인 버전** 복원

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **산출물 저장소**: 범용 파일•패키지의 내용과 버전을 저장하는 시스템 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **실험 추적**: 후보 모델의 실행 조건•매개변수•지표와 산출물을 비교하는 관리 체계 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

| 관리 체계 | 모델 레지스트리 | 산출물 저장소 | 실험 추적 |
|:---|:---|:---|:---|
| 적용 기준 | **모델 배포•롤백** | 범용 **파일•패키지 저장** | 후보 **실험 비교** |
| 핵심 특징 | **모델 계보•승인**•상태 관리 | **파일•패키지 버전** 저장 | **실행 조건•지표** 비교 |
| 한계 | 실제 **파일 저장소** 연계 필요 | **모델 승인**의미 부족 | **배포 상태** 관리 부족 |

#### 한줄 요약

- 후보 실험 기록과 승인 모델의 **배포 상태 관리** 비교

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **평가•배포 버전 불일치**: 평가한 모델과 실제 배포한 산출물의 내용이 달라지는 문제 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **미승인 모델 배포**: 별칭 전환 오류나 권한 우회로 검증되지 않은 버전이 운영에 연결되는 문제 역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 산출물 변경으로 **평가•배포 버전** 불일치 | **불변 해시•계보•평가 증적** 결합 | 모델 승인 **재현성 확보** |
| 별칭 전환 오류로 **미승인 모델 배포** | **승인 정책•원자적 별칭 전환** | 운영 모델 **승격 통제** |

#### 한줄 요약

- 산출물•계보•평가 결과가 일치하는 불변 버전에만 운영 별칭을 옮긴다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **승인 증적**: 불변 모델 버전이 배포 기준을 통과했음을 보여 주는 계보•평가•승인 기록하는 개념을  역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.
- **롤백**: 운영 이상 시 배포 별칭을 이전에 승인된 모델 버전으로 되돌리는 조치을  역할을 수행하는 핵심 기술 및 개념하는 특징을 가짐.

</details>
- **승인 증적**을 충족한 불변 버전만 승격하고 이상 시 롤백

#### 한줄 요약

- 계보•승인 기록을 남기고 **운영 별칭**은 검증 버전에만 연결
