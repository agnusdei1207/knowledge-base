## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **최초 토큰 지연(Time to First Token, TTFT)**: 요청을 보낸 시점부터 첫 출력 토큰을 받을 때까지 걸린 시간.
- **초기 반응성**: 사용자가 요청한 뒤 응답이 시작되기까지 체감하는 서비스 속성.

</details>

- 정의: 요청 전송부터 첫 출력 토큰 수신까지 걸리는 **TTFT**
- 배경/필요성: 대규모 언어 모델(LLM) 기반의 실시간 대화형 서비스에서 전체 응답 완료 시간(End-to-End Latency)만을 단일 지표로 관리할 경우, 사용자가 인지하는 초기 응답 반응성(Interactive Responsiveness) 저하의 근본 원인이 요청 큐 대기 시간인지, 방대한 프롬프트 입력에 따른 프리필(Prefill) 연산 부하인지, 혹은 생성 토큰 수 증가 때문인지 분리 식별할 수 없는 한계가 존재함에 따라, 요청 전송 시점부터 최초 생성 토큰이 클라이언트에 수신되기까지의 순수 소요 시간을 정밀 계측하는 최초 토큰 지연(TTFT: Time to First Token) 지표를 도입하여 **프리필(Prefill) 단계의 연산 병목 및 큐 대기열(Queue Wait Time) 지연의 독립적 분리 관측, 프롬프트 캐싱(Prompt Caching) 및 청크 프리필(Chunked Prefill) 도입 효과의 정량적 평가, 대화형 AI 서비스의 체감 반응성 보장을 위한 엄격한 P95/P99 초기 지연 SLO 확립**을 달성할 필요

#### 한줄 요약
- **첫 출력 토큰 수신**을 앞당기려 배치를 작게 잡으면 GPU 활용률과 처리량이 떨어지므로, TTFT 목표는 곧 처리량을 얼마나 내줄지에 대한 선언이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **백분위수(Percentile)**: 측정값의 특정 비율이 그 값 이하에 놓이는 지점이다.
- **95백분위 최초 토큰 지연(95th Percentile Time to First Token, p95 TTFT)**: 전체 요청의 95%가 이 값 이하에서 첫 토큰을 받는 꼬리 지연 경계다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 서비스가 달성해야 하는 지연•가용성 같은 내부 운영 목표다.

</details>

- **종단 간 측정**: 첫 토큰 수신 시각과 요청 전송 시각의 차
- **구간 지연**: 네트워크•대기열•프리필•첫 전송 합산
- **초기 반응성 SLO**: 평균과 p95•p99 병행 관리

#### 한줄 요약
- **대기열•프리필**과 입구•첫 전송의 합산 지연

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **프리필(Prefill)**: 입력 토큰 전체의 어텐션을 계산하여 생성에 필요한 K•V 상태를 만드는 단계다.
- **요청 대기열**: 실행 자원이 배정되기 전 요청이 부하와 우선순위에 따라 기다리는 영역.
- **스트리머**: 생성된 첫 토큰을 직렬화해 전송하고 클라이언트 수신 경계와 연결하는 구성요소다.
- **API Gateway(Application Programming Interface Gateway)**: 연결•인증•라우팅을 처리하는 요청 입구다.
- **KV Cache(Key-Value Cache)**: 프리필의 K•V 상태를 저장해 생성에 재사용하는 메모리다.

</details>

```text
[TTFT(최초 토큰 지연) 계측 아키텍처]
├── [진입 및 라우팅 계층 (Ingress Gateway)]
│   ├── 요청 타임스탬프 태깅 (Timestamp)
│   └── 인증/인가 및 서빙 인스턴스 라우팅
├── [스케줄링 및 큐잉 계층 (Scheduler & Queue)]
│   ├── 요청 대기열 (Queue Wait Time)
│   └── 연속 배치(Continuous Batching) 스케줄링
├── [프리필 연산 엔진 (Prefill Compute Engine)]
│   ├── 프롬프트 어텐션 연산 (FLOPs-bound)
│   ├── 프롬프트 캐시(Prefix Cache) 조회
│   └── 초기 KV Cache 생성 및 첫 토큰 샘플링
└── [스트리밍 전송 계층 (Streaming Egress)]
    ├── SSE/gRPC 기반 즉각 청크 직렬화
    └── 클라이언트 최초 청크 수신 (TTFT 완료)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 진입 및 라우팅 | 요청 타임스탬프 기록, TLS 핸드셰이크 및 최적 서빙 워커 라우팅 |
| 스케줄링 및 큐잉 | GPU 가용도에 따른 대기열 관리 및 연속 배치 슬롯 동적 할당 |
| 프리필 연산 엔진 | 입력 프롬프트 병렬 어텐션 계산 및 최초 출력 토큰 샘플링 수행 |
| 스트리밍 전송 계층 | 생성된 첫 번째 토큰을 SSE 청크로 직렬화하여 클라이언트에 즉시 전송 |

#### 한줄 요약
- **클라이언트•대기열**과 입구•프리필•스트리머 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **측정 경계**: TTFT 시작을 클라이언트 송신, 종료를 첫 토큰 수신으로 일관되게 정한 시점 기준이다.
- **구간 지연**: 입구 처리•대기•프리필•첫 전송처럼 전체 TTFT를 구성하는 단계별 소요 시간이다.
- **GPU(Graphics Processing Unit)**: 프리필과 토큰 생성을 병렬 처리하는 연산 장치다.

</details>

```text
클라이언트
    │ 요청 전송
    ▼
게이트웨이
    │ 1. 입구 처리•대기열 전달
    ▼
대기열•스케줄러
    │ 2. 배치•GPU 할당 전달
    ▼
프리필 엔진
    │ 3. 첫 토큰 전달
    ▼
스트리머
    │ 첫 토큰 수신
    ▼
클라이언트
```

### 동작 원리

1. 입구 처리•대기열 전달: 인증•라우팅 후 **대기 상태**로 전환
2. 배치•GPU 할당 전달: 실행 배치와 **연산 자원** 배정
3. 첫 토큰 전달: 프리필 결과의 **첫 출력 토큰** 제공

#### 한줄 요약
- **송신•수신 경계**와 구간 지연 기반 병목 분리

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **토큰당 출력 지연(Time per Output Token, TPOT)**: 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 시간을 측정한다.
- **종단 간 지연**: 요청 전송부터 마지막 토큰 수신까지 전체 완료 시간을 측정한다.

</details>

| 구분 | TTFT | TPOT | 종단 간 지연 |
|:---|:---|:---|:---|
| 적용 기준 | **초기 반응성 관리** | **스트리밍 지속 속도 관리** | **전체 완료 시간 관리** |
| 핵심 특징 | 요청부터 **첫 토큰 수신** | 첫 토큰 뒤 **토큰당 평균 시간** | 요청부터 **마지막 토큰 수신** |
| 한계 | **지속 생성 속도 미반영** | **초기 대기시간 미반영** | **단계별 병목 구분 곤란** |

#### 한줄 요약
- 시작은 **TTFT**, 지속은 **TPOT**, 완료는 종단 간 지연

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **프롬프트 캐시(Prompt Cache)**: 동일 입력 접두사의 프리필 결과를 저장하여 반복 요청에서 재사용하는 캐시다.
- **꼬리 지연**: 평균보다 크게 늦은 일부 요청에서 발생하며 p95•p99로 관찰하는 지연.
- **우선순위 큐**: 요청 중요도와 지연 목표에 따라 GPU 배정 순서를 다르게 관리하는 대기열이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 길이 증가의 **프리필 지연** | 길이 구간별 **SLO•프롬프트 축약** 적용 | 초기 응답 지연 **관리** |
| 배치 대기의 **꼬리 지연 증가** | **우선순위 큐•최대 대기시간** 설정 | p95•p99 지연 **완화** |
| 시스템별 **측정 경계 불일치** | **클라이언트 송신•수신 기준** 통일 | 지표 비교 가능성 **확보** |

#### 한줄 요약
- **꼬리 지연•측정 경계**와 입력 길이 구간 통합 관리

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **스케줄링 개선**: TTFT 병목이 대기열에 있을 때 우선순위와 최대 대기시간을 조정하는 대책.
- **입력 축약•캐싱**: 병목이 프리필에 있을 때 입력 토큰을 줄이거나 동일 접두사 계산을 재사용하는 대책.

</details>

- 대화형 생성 AI 서비스의 사용자 경험(UX)과 초기 반응성을 결정짓는 **LLM 추론 서빙 인프라의 핵심 서비스 수준 지표(TTFT / Prefill Compute Bound / Queue Wait Latency / Prompt Caching & Chunked Prefill / P95·P99 Interactive SLO)의 절대적 표준 메트릭**으로 확고히 자리 잡았으며, TPOT(토큰당 생성 지연)과의 분리 계측 체계로 정착된 가운데, 실무 프로덕션 서빙 파이프라인 구축 시에는 **반복되는 시스템 프롬프트 및 Few-shot 예시의 프리필 지연을 제거하는 Prefix Caching 적용, 긴 프롬프트 유입 시 디코딩 멈춤 현상(Jank)을 방지하는 Chunked Prefill 스케줄러 도입, P95/P99 꼬리 지연을 실시간 추적하여 스케일아웃 및 우선순위 큐(Priority Queue) 라우팅을 자동 트리거하는 관측성 체계 연계**를 결합하여 완벽한 실시간 반응성과 안정적인 서빙 SLA를 완성

#### 한줄 요약
- **p95 병목 구간**에 따라 지연 대책 결정
