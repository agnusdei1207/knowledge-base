## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **최초 토큰 지연(Time to First Token, TTFT)**: 요청을 보낸 시점부터 첫 출력 토큰을 받을 때까지 걸린 시간을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **초기 반응성**: 사용자가 요청한 뒤 응답이 시작되기까지 체감하는 서비스 속성을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- 정의/개념: 요청 전송부터 첫 출력 토큰 수신까지의 초기 응답 지연인 **TTFT**임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 배경/필요성: 전체 응답 시간만으로는 **대기열•프리필•첫 전송 병목**을 분리하기 어렵음.

#### 한줄 요약
- 요청 전송부터 **첫 출력 토큰 수신**까지의 지연 구조 구현

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **백분위수(Percentile)**: 측정값을 작은 순서로 배열했을 때 특정 비율이 그 값 이하에 놓이는 지점로 정의된다.
- **95백분위 최초 토큰 지연(95th Percentile Time to First Token, p95 TTFT)**: 전체 요청의 95%가 이 값 이하에서 첫 토큰을 받는 꼬리 지연 경계다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 서비스가 달성해야 하는 지연•가용성 같은 내부 운영 목표다.

</details>

- `TTFT = 첫 토큰 수신 시각 - 요청 전송 시각`의 **TTFT 종단 간 측정**이 핵심임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 네트워크•대기열•프리필•첫 전송을 합산하는 **구간 지연 지표**가 핵심임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 평균과 p95•p99를 병행하는 **초기 반응성 SLO**로 관리하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **입구•대기열•프리필•첫 전송**의 합산 지연 구조 구현

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **프리필(Prefill)**: 입력 토큰 전체의 어텐션을 계산하여 생성에 필요한 K•V 상태를 만드는 단계다.
- **요청 대기열**: 실행 자원이 배정되기 전 요청이 부하와 우선순위에 따라 기다리는 영역을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **스트리머**: 생성된 첫 토큰을 직렬화해 전송하고 클라이언트 수신 경계와 연결하는 구성요소다.
- **API Gateway(Application Programming Interface Gateway)**: 연결•인증•라우팅을 처리하는 요청 입구다.
- **KV Cache(Key-Value Cache)**: 프리필의 K•V 상태를 저장해 생성에 재사용하는 메모리다.

</details>

```text
[클라이언트]──[API Gateway]──[요청 대기열]
                                   │
                              [프리필 엔진]──[스트리머]
```

선의 의미: 종단 측정•입구•대기•프리필•전송 책임의 정적 연결을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 클라이언트 | 요청 전송과 첫 토큰 수신의 **종단 시각 기록** |
| API Gateway | 연결•인증•라우팅의 **입구 처리 시간 형성** |
| 요청 대기열 | 부하•우선순위에 따른 **배치 대기 시간 형성** |
| 프리필 엔진 | 입력 어텐션과 초기 **KV Cache 기반 첫 토큰 준비** |
| 스트리머 | 첫 토큰 직렬화•전송과 **수신 경계 연결** |

#### 한줄 요약
- **클라이언트•입구•대기열•프리필•스트리머**를 구성 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **측정 경계**: TTFT 시작을 클라이언트 송신, 종료를 첫 토큰 수신으로 일관되게 정한 시점 기준을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **구간 지연**: 입구 처리•대기•프리필•첫 전송처럼 전체 TTFT를 구성하는 단계별 소요 시간을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **GPU(Graphics Processing Unit)**: 프리필과 토큰 생성을 병렬 처리하는 연산 장치다.

</details>

```text
클라이언트
    │ 요청 전송
    ▼
게이트웨이
    │ 1. 입구 처리•대기열 전달
    ▼
대기열•스케줄러
    │ 2. 배치•GPU 할당 전달
    ▼
프리필 엔진
    │ 3. 첫 토큰 전달
    ▼
스트리머
    │ 첫 토큰 수신
    ▼
클라이언트
```

1. **입구 처리•대기열 전달**: 인증•라우팅 후 **대기 상태**를 전환함.
2. **배치•GPU 할당 전달**: 실행 배치와 **연산 자원**을 배정함.
3. **첫 토큰 전달**: 프리필 결과의 **첫 출력 토큰**을 제공함.

#### 한줄 요약
- **송신•수신 경계•구간 지연**으로 병목을 분리 체계 적용

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **토큰당 출력 지연(Time per Output Token, TPOT)**: 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 시간을 측정한다.
- **종단 간 지연**: 요청 전송부터 마지막 토큰 수신까지 전체 완료 시간을 측정한다.

</details>

| 비교 기준 | TTFT | TPOT | 종단 간 지연 |
|:---|:---|:---|:---|
| 적용 기준 | **초기 반응성 관리** | **스트리밍 지속 속도 관리** | **전체 완료 시간 관리** |
| 핵심 특징 | 요청부터 **첫 토큰 수신** | 첫 토큰 뒤 **토큰당 평균 시간** | 요청부터 **마지막 토큰 수신** |
| 한계 | **지속 생성 속도 미반영** | **초기 대기시간 미반영** | **단계별 병목 구분 곤란** |

#### 한줄 요약
- 시작은 **TTFT**, 지속은 **TPOT**, 완료는 **종단 간 지연**으로 구분 체계 적용

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **프롬프트 캐시(Prompt Cache)**: 동일 입력 접두사의 프리필 결과를 저장하여 반복 요청에서 재사용하는 캐시다.
- **꼬리 지연**: 평균보다 크게 늦은 일부 요청에서 발생하며 p95•p99로 관찰하는 지연을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **우선순위 큐**: 요청 중요도와 지연 목표에 따라 GPU 배정 순서를 다르게 관리하는 대기열을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 길이 증가의 **프리필 지연** | 길이 구간별 **SLO•프롬프트 축약** 적용 | 초기 응답 지연 **관리** |
| 배치 대기의 **꼬리 지연 증가** | **우선순위 큐•최대 대기시간** 설정 | p95•p99 지연 **완화** |
| 시스템별 **측정 경계 불일치** | **클라이언트 송신•수신 기준** 통일 | 지표 비교 가능성 **확보** |

#### 한줄 요약
- **길이 구간•꼬리 지연•측정 경계**를 함께 관리 체계 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **스케줄링 개선**: TTFT 병목이 대기열에 있을 때 우선순위와 최대 대기시간을 조정하는 대책을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **입력 축약•캐싱**: 병목이 프리필에 있을 때 입력 토큰을 줄이거나 동일 접두사 계산을 재사용하는 대책을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- p95 초과가 대기열이면 **스케줄링**, 프리필이면 **입력 축약•프롬프트 캐시**를 적용하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **p95 병목 구간**에 따라 스케줄링•프리필 대책을 선택 체계 적용
