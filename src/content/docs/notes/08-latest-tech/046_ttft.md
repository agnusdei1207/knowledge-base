## 미리 알고가기

- **TTFT(Time To First Token, 티티에프티)**: 영문 머리글자를 딴 지표로, 요청 전송부터 첫 출력 토큰 수신까지의 시간
- **KV 캐시 (Key-Value Cache)**: 입력 어텐션 값을 저장하는 메모리
- **GPU (Graphics Processing Unit)**: 프리필과 디코드 연산 수행 장치
- **TPOT(Time Per Output Token, 티피오티)**: 첫 토큰 뒤 출력 토큰당 평균 생성 시간
- **E2E 지연(End-to-End Latency, 엔드투엔드 지연)**: 요청부터 마지막 토큰 수신까지의 전체 시간
- **SLO(Service Level Objective, 에스엘오)**: 서비스가 달성해야 할 꼬리 지연 목표
- **SSE (Server-Sent Events)**: 토큰 스트림 전달 프로토콜


## Ⅰ. 개요

- 정의/개념: 요청부터 첫 출력 토큰까지의 지연
- 기존 한계: 전체 응답 시간만으로 초기 대기 병목 분리 곤란
- **배경/필요성**: 대기열·프리필·첫 전송의 초기 응답성 측정

### 쉽게 이해하기 (학습용)
- 질문 후 화면에 첫 답변이 나타나기까지 기다린 시간임

## Ⅱ. 특징

- 요청 전송·대기열·프리필·첫 토큰 전송 시간을 포함한다
- 입력 길이·배치 대기·동시 부하가 TTFT를 좌우한다
- 평균과 p95·p99를 함께 측정해 꼬리 지연을 관리한다

### 쉽게 이해하기 (학습용)

- 첫 토큰 지연은 계산뿐 아니라 대기·전송도 합친 시간이다

## Ⅲ. 구성요소 및 구조

| 구성 요소 | 설명 |
|:---|:---|
| Gateway | 연결, 인증, 라우팅 시간 처리 |
| Request Queue | 부하와 우선순위에 따른 대기시간 형성 |
| Scheduler | 배치와 GPU 자원 할당 시점 결정 |
| Prefill Engine | 입력 처리 및 초기 KV 캐시 생성 |
| Streamer | 첫 토큰 직렬화 및 전송 처리 |

> 요약: 요청 경계와 단계별 시각이 TTFT 병목을 드러냄

### 쉽게 이해하기 (학습용)

- 접수·대기·GPU 배정·입력 계산·첫 전송 중 어느 구간이 느린지 따로 계측함

## Ⅳ. 원리 및 절차 흐름도

```text
경계정의
↓
시각수집
↓
지연분해
↓
병목조정
↓
회귀검증
```

| 절차 | 설명 |
|:---|:---|
| 경계정의 | 요청부터 첫 토큰까지 정의함 |
| 시각수집 | 각 단계별 소요 시각을 수집함 |
| 지연분해 | 구간별 지연을 상세 분석함 |
| 병목조정 | 가장 큰 지연 구간을 최적화함 |
| 회귀검증 | SLO 준수 여부를 최종 검증함 |

> 요약: 구간별 TTFT를 분해해 최대 병목을 조정함

### 쉽게 이해하기 (학습용)

- TTFT를 구간별로 나눠 실제 병목을 찾아야 함

## Ⅴ. 종류 및 비교

| 판단 기준 | TTFT | TPOT | E2E 지연 |
|:---|:---|:---|:---|
| 적용 기준 | 초기 반응성 관리 | 스트리밍 속도 관리 | 전체 완료 관리 |
| 핵심 특징 | 요청부터 첫 토큰 | 첫 토큰 뒤 토큰당 시간 | 요청부터 마지막 토큰 |
| 한계 | 디코드 지속 속도 미반영 | 초기 대기시간 미반영 | 단계별 병목 구분 불가 |

> 요약: 단계별 지연을 나눠 세부 관리함

### 쉽게 이해하기 (학습용)

- 답이 시작되는 시간, 이어서 나오는 속도, 전체 답이 끝나는 시간을 나눠 보는 지표임

## Ⅵ. 실무 사례

- 입력 길이·캐시 적중률별 TTFT 목표를 나눈다

### 쉽게 이해하기 (학습용)

- 긴 입력과 혼잡한 배치는 같은 모델의 첫 답도 늦춘다

## Ⅶ. 결론

- 첫 응답 지연 개선을 위해 입력·큐·프리필 병목을 검토하여 **TTFT** 활용

### 쉽게 이해하기 (학습용)

- 첫 답을 빠르게 하려면 계산뿐 아니라 접수와 대기, 전송까지 전체 경로를 봐야 함
