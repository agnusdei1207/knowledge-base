## 미리 알고가기

- **최초 토큰 지연(Time to First Token, TTFT)**: 요청을 보낸 시점부터 첫 출력 토큰을 받을 때까지 걸린 시간
- **프리필(Prefill)**: 입력 토큰 전체의 어텐션을 계산하여 생성에 필요한 키·값 벡터를 만드는 단계
- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 키·값 벡터를 저장하여 다음 토큰 생성에 재사용하는 메모리
- **백분위수(Percentile)**: 전체 측정값을 작은 순서로 배열했을 때 특정 비율이 그 값 이하에 놓이는 지점으로, p95는 95% 요청의 상한을 의미
- **서비스 수준 목표(Service Level Objective, SLO)**: 서비스가 달성해야 하는 지연·가용성 등의 내부 운영 목표
- **토큰당 출력 지연(Time per Output Token, TPOT)**: 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 시간
- **종단 간 지연(End-to-End Latency)**: 요청 전송부터 마지막 토큰 수신까지의 전체 시간
- **프롬프트 캐시(Prompt Cache)**: 동일한 입력 접두사의 프리필 결과를 저장하여 반복 요청에서 재사용하는 캐시

## Ⅰ. 개요

- 정의/개념: **TTFT**는 요청 전송부터 첫 출력 토큰 수신까지의 초기 응답 지연
- 배경/필요성: 전체 응답 시간만으로는 **대기열·프리필·첫 전송 병목**의 분리 곤란

### 쉽게 이해하기 (학습용)
- 질문을 보낸 뒤 화면에 첫 답변 조각이 나타날 때까지 기다린 시간임

## Ⅱ. 특징

- `TTFT = 첫 토큰 수신 시각 - 요청 전송 시각`의 **종단 간 측정**
- 네트워크·대기열·프리필·첫 전송을 합산하는 **구간 지연 지표**
- 평균과 p95·p99를 병행하는 **초기 반응성 SLO**

### 쉽게 이해하기 (학습용)
- 첫 토큰이 늦는 원인은 모델 계산뿐 아니라 접수·대기·전송에도 있을 수 있음

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
    columns 3
    C["클라이언트"]
    G["API 게이트웨이"]
    Q["요청 대기열"]
    P["프리필 엔진"]
    S["스트리머"]
    C --- G
    G --- Q
    Q --- P
    P --- S
```

| 구성요소 | 책임 |
|:---|:---|
| 클라이언트 | 요청 전송과 첫 토큰 수신의 **종단 시각 기록** |
| API 게이트웨이 | 연결·인증·라우팅의 **입구 처리 시간 형성** |
| 요청 대기열 | 부하·우선순위에 따른 **배치 대기 시간 형성** |
| 프리필 엔진 | 입력 어텐션과 초기 KV 캐시의 **첫 토큰 준비** |
| 스트리머 | 첫 토큰 직렬화·전송과 **수신 경계 연결** |

### 쉽게 이해하기 (학습용)
- 접수·대기·입력 계산·첫 전송 중 어느 구간이 느린지 따로 기록함

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant C as 클라이언트
    participant G as 게이트웨이
    participant Q as 대기열·스케줄러
    participant P as 프리필 엔진
    participant S as 스트리머
    C->>G: 요청 전송
    G->>Q: 1. 입구 처리·대기열 전달
    Q->>P: 2. 배치·GPU 할당 전달
    P->>S: 3. 첫 토큰 전달
    S-->>C: 첫 토큰 수신
```

1. **입구 처리·대기열 전달**: 인증·라우팅 후 **대기 상태** 전환
2. **배치·GPU 할당 전달**: 실행 배치와 **연산 자원** 배정
3. **첫 토큰 전달**: 프리필 결과의 **첫 출력 토큰** 제공

### 쉽게 이해하기 (학습용)
- 같은 시작·종료 지점을 정한 뒤 구간별 시간을 더해 실제 병목을 찾음

## Ⅴ. 종류 및 비교

| 비교 기준 | TTFT | TPOT | 종단 간 지연 |
|:---|:---|:---|:---|
| 적용 기준 | 초기 반응성 관리 | 스트리밍 지속 속도 관리 | 전체 완료 시간 관리 |
| 핵심 특징 | 요청부터 **첫 토큰 수신** | 첫 토큰 뒤 **토큰당 평균 시간** | 요청부터 **마지막 토큰 수신** |
| 한계 | 지속 생성 속도 미반영 | 초기 대기시간 미반영 | 단계별 병목 구분 곤란 |

### 쉽게 이해하기 (학습용)
- 답이 시작되는 시간, 이어지는 속도, 전체 답이 끝나는 시간을 나눠 측정함

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 입력 길이 증가의 **프리필 지연** | 길이 구간별 SLO·프롬프트 축약 적용 | 초기 응답 지연 **관리** |
| 배치 대기의 **꼬리 지연 증가** | 우선순위 큐·최대 대기시간 설정 | p95·p99 지연 **완화** |
| 시스템별 **측정 경계 불일치** | 클라이언트 송신·수신 기준 통일 | 지표 비교 가능성 **확보** |

### 쉽게 이해하기 (학습용)
- 긴 입력과 혼잡한 대기를 나누어 측정하고 같은 기준으로 비교함

## Ⅶ. 결론

- p95 초과가 대기열이면 **스케줄링**, 프리필이면 **입력 축약·프롬프트 캐시** 적용

### 쉽게 이해하기 (학습용)
- 평균만 보지 않고 가장 늦은 요청이 어느 구간에서 지연되는지 찾아 개선함
