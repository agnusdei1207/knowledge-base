## 미리 알고가기

- **하이브리드 클라우드**: 온프레미스와 공용 클라우드를 연결하여 운용함
- **멀티클라우드**: 복수 사업자의 클라우드를 선택적으로 사용함
- **데이터 위치**: 데이터 경계와 네트워크 연결, 운영 일관성이 핵심임



## Ⅰ. 개요

- 정의/개념: 사설 환경과 공용 클라우드를 연결해 운영
- 기존 한계: 사설 환경만으로는 급격한 수요에 탄력적으로 확장하거나 다양한 관리형 서비스를 신속하게 활용하기 어렵다.

### 쉽게 이해하기 (학습용)

- 내부 창고와 외부 센터를 전용 통로로 연결하여 보관·처리를 분담함

## Ⅱ. 특징

- **워크로드 배치**: 규제·지연·확장 요구에 따라 실행 환경을 정한다.
- **데이터 경계**: 위치·복제·일관성 규칙으로 환경 간 이동을 통제한다.
- **연결·복구**: 회선 지연과 단절을 고려해 독립 운영과 복구를 설계한다.

### 쉽게 이해하기 (학습용)

- 중요한 원본은 내부 창고에 두고 외부에는 필요한 물량만 보냄

## Ⅲ. 아키텍처 및 구성요소
```text
[온프레미스·사설 환경] ⇄ 전용 연결·신원·데이터 동기화 ⇄ [공용 클라우드]
   system of record                                      탄력적 front-end·분석
          └────────── 공통 정책·배포·관측 ──────────────┘
```
| 설계 요소 | 설명 |
|:---|:---|
| 워크로드 배치 | 규제·데이터 중력·지연 등을 기준으로 실행 환경 결정 |
| 연결·해석 | 이중화 회선·라우팅·DNS와 대역폭·지연 설계 |
| 보안 통제 | 신원 federation·권한·키 관리로 신뢰 경계 구성 |
| 데이터 통합 | 원본·복제본·동기화·스키마 등 정합성 확보 |
| 공통 플랫폼 | 정책·배포·관측·비용을 통합적으로 운용함 |
> 요약: 독립 환경 간 연결·신원·데이터 정합성 확보
### 쉽게 이해하기 (학습용)
- 전용도로와 출입증, 재고 동기화 규칙 마련
## Ⅳ. 원리 및 절차 흐름도

```text
분류
  ↓
설계
  ↓
연결
  ↓
전환
  ↓
검증
```

| 절차 | 설명 |
|:---|:---|
| 분류 | 규제·지연·확장 요구로 대상을 구분함 |
| 설계 | 실행 위치와 데이터 원본을 결정함 |
| 연결 | 회선·신원·정책·관측을 통합함 |
| 전환 | 복제 확인 및 데이터 동기화 수행함 |
| 검증 | 단절·장애 훈련으로 복원력 확보함 |

> 요약: 분류 후 환경 간 연결과 데이터 정합성을 검증함

### 쉽게 이해하기 (학습용)

- 창고와 경로를 정하고 출입증 검증 후 재고 이동과 단절 훈련을 수행함

## Ⅴ. 클라우드 운영 모델 비교

| 판단 기준 | 하이브리드 | 멀티 | 사설 |
|:---|:---|:---|:---|
| 적용 기준 | 환경 간 이동·배치 | 지역·복원력 배치 | 전용 통제권 확보 |
| 핵심 특징 | 사설·공용 연결 | 복수 클라우드 사용 | 전용 환경 운영 |
| 한계 | 연계 복잡성·지연 | 통제·전송 비용 | 확장성·서비스 제약 |

> 요약: 사설·공용 환경 간 데이터 이동 및 통제 경계를 설계함

### 쉽게 이해하기 (학습용)

- 내부 창고와 외부 창고를 잇는 방식, 여러 외부 회사를 쓰는 방식, 내부 전용 창고만 쓰는 방식은 물품 이동과 통제 범위가 다름

## Ⅵ. 실무 사례

1. 제조 설비 제어는 사설 환경에 두고 예측 분석은 공용 클라우드에서 수행

### 쉽게 이해하기 (학습용)

- 민감한 제어와 원본은 현장에 유지하고 승인 데이터만 분석 환경으로 전송함

## Ⅶ. 결론

- 전용 환경의 통제와 퍼블릭 클라우드의 확장성을 결합하기 위해 **데이터 경계·연결 지연·정합성·단절 복구·이중 운영비**를 검토하고, 연결 편익이 큰 업무에 하이브리드 클라우드를 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 두 장소의 장점만 기대하지 말고 무엇을 어디에 둘지, 통로가 끊기면 어떻게 일할지, 두 곳을 계속 관리할 가치가 있는지까지 판단해야 함
