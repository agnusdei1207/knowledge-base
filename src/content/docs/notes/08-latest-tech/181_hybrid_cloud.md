## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **하이브리드 클라우드(Hybrid Cloud)**: 온프레미스•사설 클라우드와 공용 클라우드를 연결해 하나의 운영 모델로 사용하는 방식이다.
- **온프레미스(On-Premises)**: 조직이 직접 통제하는 시설에 정보시스템을 구축•운영하는 형태이다.

</details>

- 정의/개념: **하이브리드 클라우드**는 사설 환경과 공용 클라우드를 통합 운영하는 모델이다.
- 배경/필요성: 규제•기존 시스템 제약으로 내부 환경만으로는 **급증 수요•관리형 서비스** 수용하기 어렵다.

#### 한줄 요약

- 중요한 물품은 내부에 두고 급증 수요는 연결된 외부 클라우드에서 처리한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **데이터 중력**: 데이터 규모가 커질수록 응용 프로그램과 서비스가 데이터 위치 가까이에 모이는 성질이다.
- **연결 단절 내성**: 환경 간 회선이 끊겨도 각 환경이 제한된 기능을 독립 수행하고 복구 후 동기화하는 능력이다.

</details>

- **1. 정책 기반 배치**: 규제, 지연, 데이터 중력, 비용에 따라 업무와 데이터의 실행 위치를 결정한다.
- **2. 환경 간 일관성**: 신원, 보안, 배포, 관측 정책을 서로 다른 플랫폼에 공통을 적용한다.
- **3. 연결 단절 내성**: 회선 지연•장애를 전제로 동기화와 독립 운영 및 복구 경로를 설계한다.

#### 한줄 요약

- 업무 성격에 따라 실행 위치를 정하고 연결 단절에도 독립 운영할 수 있게 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **페더레이션(Federation)**: 서로 다른 신원•관리 영역이 신뢰 관계를 맺어 자원을 공동 사용하는 방식이다.
- **데이터 통합**: 사설•공용 환경 사이의 원본•복제본을 동기화하고 정합성을 유지하는 기능이다.
- **사설 환경**: 조직 전용 자원과 정책으로 규제•지연 민감 업무를 운영하는 영역이다.
- **공용 클라우드**: 외부 사업자의 공유 자원에서 탄력적 처리 용량과 관리형 서비스를 제공하는 영역이다.
- **연결 계층**: 두 환경 사이의 네트워크 경로•라우팅•암호화를 제공하는 구성요소이다.
- **통합 신원**: 동일한 사용자•서비스 신원을 두 환경에서 공통으로 식별하는 체계이다.
- **보안 정책**: 접근 권한과 보호 규칙을 두 환경의 경계에 일관되게 적용하는 기준이다.

</details>

```text
                 [사설 환경]
                      |
                 [연결 계층]
                      |
                 [신원•보안]
                      |
                 [데이터 통합]
                      |
               [공용 클라우드]
```

선의 의미: 사설 환경과 공용 클라우드를 연결 계층이 결합하고, 신원•보안과 데이터 통합이 두 환경에 공통으로 적용되는 통제 경계를 구성한다.

| 구성요소 | 책임 |
|:---|:---|
| 사설 환경 | 규제•지연 민감 **업무•원본 데이터** 운영 |
| 연결 계층 | 전용 회선•가상 사설망 기반 **환경 간 연결** |
| 신원•보안 | 페더레이션•최소 권한 기반 **공통 통제** |
| 데이터 통합 | 원본•복제본의 **동기화•정합성** 관리 |
| 공용 클라우드 | **탄력적 처리 용량•관리형 서비스** 제공 |

#### 한줄 요약

- 사설•공용 환경을 연결하고 신원과 데이터 규칙을 공동 운영한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **배치 정책**: 규제•지연•데이터 위치•비용에 따라 워크로드의 사설•공용 실행 위치를 정한 규칙이다.
- **통합 운영**: 서로 다른 환경의 배포•확장•관측•복구 상태를 공통 기준으로 관리하는 활동이다.

</details>

```text
[업무 담당] ── 워크로드 요구 ──▶ [배치 정책]
                                      ├─ 1. 사설 실행 조건 ──▶ [사설 환경]
                                      └─ 2. 공용 실행 조건 ──▶ [공용 클라우드]
[사설 환경] ── 3. 동기화 데이터 ──▶ [공용 클라우드]
[공용 클라우드] ── 4. 워크로드 상태 ──▶ [통합 운영]
[업무 담당] ◀──────── 통합 운영 결과 ──────── [통합 운영]
```

**동작 원리**

1. **사설 실행 조건 전달**: 규제•지연•데이터 원본의 **사설 배치 조건**을 제공한다.
2. **공용 실행 조건 전달**: 확장•관리형 서비스의 **공용 배치 조건**을 제공한다.
3. **동기화 데이터 전달**: 원본•복제본의 **정합성 상태**와 변경분을 제공한다.
4. **워크로드 상태 전달**: 배포•확장•이관의 **운영 상태**를 제공한다.

#### 한줄 요약

- 각 단계의 판정 결과가 다음 주체의 실행 조건으로 이어지는 흐름이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **멀티클라우드**: 둘 이상의 공용 클라우드 제공자를 목적별로 함께 사용하는 전략이다.
- **사설 클라우드**: 조직 전용 자원과 정책으로 클라우드 운영 기능을 제공하는 환경이다.

</details>

| 구분 | 하이브리드 클라우드 | 멀티클라우드 | 사설 클라우드 |
|:---|:---|:---|:---|
| 적용 대상 | **사설•공용 환경 간 업무 분담** | 복수 사업자의 **서비스 조합** | **전용 통제**가 필요한 업무 |
| 핵심 방식 | 환경 간 연결•이동과 **공통 운영** | 사업자별 **장점•복원력** 활용 | 조직 전용 **자원•정책 운영** |
| 주요 한계 | **연계 복잡성•이중 운영비** | **정책 분산•전송 비용** | **확장 용량•서비스 선택** 제약 |

#### 한줄 요약

- 적용 기준과 핵심 특징 및 한계를 함께 비교해 대안을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **단일 원본**: 충돌을 막도록 특정 데이터의 최종 갱신 권한을 한 환경에 부여한 기준이다.
- **회로 차단기**: 환경 간 호출이 반복 실패할 때 요청을 일시 차단해 연쇄 장애를 막는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **데이터 정합성** 미검증 시 양방향 갱신 충돌과 오래된 복제본 사용 | 단일 원본 지정, 동기화 방향•충돌 정책, 복제 지연 감시 | 환경 간 **복제 정합성** 향상 |
| **연결 단절** 미검증 시 환경 간 호출이 연쇄 실패하고 업무 중단 | 이중화 회선, 시간 초과•회로 차단, 독립 운영 모드와 복구 훈련 | **연쇄 실패 범위** 축소 |
| **정책•비용 분산** 미검증 시 환경별 권한•배포 편차와 중복 자원 비용 증가 | 정책 코드화, 공통 자산 목록•관측, 총소유비용과 반출 비용 정기 검토 | 정책 편차•**중복 비용** 감소 |

#### 한줄 요약

- 핵심 운영 위험마다 실행 가능한 대책과 검증 효과를 함께 확인한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **탄력 수요**: 시간에 따라 크게 변해 공용 클라우드의 자동 확장이 유리한 처리 요구량이다.
- **총소유비용(Total Cost of Ownership, TCO)**: 구축•운영•연결•인력•반출을 포함해 수명주기 전체에 드는 비용이다.

</details>

- 규제•지연 민감 업무는 **사설 환경**, 탄력 수요는 **공용 클라우드**에 배치하고 **TCO**로 판단이 핵심이다.

#### 한줄 요약

- 핵심 판단 기준을 먼저 정한 뒤 적용 범위를 결정하는 것이 중요하다.
