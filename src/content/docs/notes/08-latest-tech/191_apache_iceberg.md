## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Apache Iceberg**: 스냅샷•매니페스트 계층으로 대규모 분석 테이블의 유효 파일과 스키마를 관리하는 오픈 테이블 형식로 정의된다.
- **오픈 테이블 형식**: 객체 저장소 파일 위에 공개된 메타데이터•스냅샷•커밋 규칙을 제공하는 계층을 의미한다.

</details>

- 정의: 스냅샷•매니페스트 계층으로 파일과 스키마를 관리하는 **Apache Iceberg**
- 배경/필요성: 전통적인 하이브 메타스토어(Hive Metastore) 방식은 파일 시스템의 디렉터리 경로 구조로 파티션을 관리하여 대규모 데이터셋 쿼리 시 디렉터리 리스팅(O(N) 파일 스캔) 병목이 발생하고, 파티션 컬럼 변경 시 테이블 전체를 다시 써야 하며, 다중 작업자의 동시 쓰기 시 원자적 커밋(Atomic Commit)을 지원하지 못하는 근본적 한계에 직면함에 따라, 넷플릭스(Netflix)에서 시작되어 아파치 재단 표준으로 자리 잡은 오픈 테이블 포맷인 Apache Iceberg(Snapshot-Manifest Tree Architecture / Catalog $\rightarrow$ Table Metadata $\rightarrow$ Manifest List $\rightarrow$ Manifest File $\rightarrow$ Data/Delete Files, Hidden Partitioning, Partition Evolution, In-place Schema Evolution with Field-ID, Optimistic Concurrency Control, Row-level Deletes: Copy-on-Write vs Merge-on-Read, Time Travel)를 도입하여 **스냅샷 기반 계층형 매니페스트 트리(Tree of Manifests) 구조를 통한 $O(1)$ 초고속 메타데이터 프루닝 및 디렉터리 리스팅 오버헤드 100% 제거, 고유 Field-ID 기반의 인플레이스 스키마 진화 및 무중단 파티션 진화(Partition Evolution) 지원, 스파크(Spark), 트리노(Trino), 플링크(Flink), 스노우플레이크(Snowflake) 등 이기종 다중 컴퓨팅 엔진 간 완벽한 ACID 트랜잭션 상호운용성**을 달성할 필요

#### 한줄 요약

- Iceberg는 디렉터리 나열을 스냅샷 메타데이터 조회로 대체해 **유효 파일•스키마 관리** 비용을 파일 수와 떼어 놓는 대신, 메타데이터 파일 자체가 쌓여 별도 정리 대상이 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **매니페스트(Manifest)**: 스냅샷이 참조하는 데이터•삭제 파일과 파티션•열 통계를 기록한 메타데이터을 의미한다.
- **숨은 파티셔닝(Hidden Partitioning)**: 질의가 물리 파티션 열을 직접 알지 않아도 필터를 자동 변환해 파일을 선별하는 기능을 의미한다.
- **필드 식별자(Field Identifier, Field ID)**: 이름 변경과 무관하게 스키마 열을 추적하는 고유 번호을 말한다.

</details>

- 스냅샷•매니페스트 계층 기반 **데이터•삭제 파일 추적**
- Field ID 기반 **스키마 진화•숨은 파티셔닝**
- 매니페스트 통계 기반 **파일 프루닝•메타데이터 관리**
#### 한줄 요약

- **숨은 파티션 파일 프루닝**은 질의가 파티션 표현식을 몰라도 되게 만들어 사용자 실수를 없애는 대신, 파티션 규칙이 메타데이터에 묶여 그 변경 이력까지 함께 관리해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **카탈로그**: 현재 테이블 메타데이터 포인터를 원자적으로 교체하는 관리 계층을 말한다.
- **삭제 파일**: 데이터 파일을 다시 쓰지 않고 삭제할 행이나 위치를 기록한 파일로 정의된다.

</details>

```text
[Apache Iceberg 메타데이터 트리]
├── [카탈로그 계층]
│   └── [카탈로그]
├── [메타데이터 계층]
│   ├── [테이블 메타데이터]
│   ├── [스냅샷•매니페스트 목록]
│   └── [매니페스트]
└── [데이터 스토리지 계층]
    └── [데이터•삭제 파일]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 카탈로그 | 현재 메타데이터 포인터의 **원자적 교체** |
| 테이블 메타데이터 | 스키마•파티션 명세와 **스냅샷 이력** 관리 |
| 스냅샷•매니페스트 목록 | 특정 시점 상태와 **매니페스트 연결** |
| 매니페스트 | 파일 경로•파티션과 **열 통계** 기록 |
| 데이터•삭제 파일 | 행 데이터와 **행•위치 삭제 정보** 저장 |

#### 한줄 요약

- 현재 스냅샷의 **메타데이터 트리•유효 파일 식별**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **기준 스냅샷**: 쓰기 작업이 변경을 시작할 때 참조한 현재 테이블 상태을 의미한다.
- **원자 커밋**: 기준 포인터가 바뀌지 않았는지 확인한 뒤 새 메타데이터 포인터를 한 번에 게시하는 연산을 말한다.

</details>

```text
[쓰기 엔진] ── 1. 기준 스냅샷 조회 ──▶ [카탈로그]
[쓰기 엔진] ◀──── 기준 스냅샷 반환 ──── [카탈로그]
[쓰기 엔진] ── 2. 데이터•삭제 파일 생성 ──▶ [데이터•삭제 파일]
[쓰기 엔진] ── 3. 매니페스트•메타데이터 생성 ▶ [매니페스트•메타데이터]
[쓰기 엔진] ── 4. 포인터 비교•원자 커밋 ──▶ [카탈로그]
[읽기 엔진] ◀──── 확정 스냅샷 제공 ───── [카탈로그]
```

### 동작 원리

1. 기준 스냅샷 조회: 현재 **스키마•파티션•파일 상태** 확인
2. 데이터•삭제 파일 생성: 변경 행과 **삭제 정보•열 통계** 기록
3. 매니페스트•메타데이터 생성: 신규 파일과 **스냅샷 연결 정보** 기록
4. 포인터 비교•원자 커밋: 기준 일치 시 **새 스냅샷 게시**

#### 한줄 요약

- 신규 메타데이터 생성 후 **원자 포인터 교체•상태 공개**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Delta Lake**: 순차 트랜잭션 로그와 체크포인트로 테이블 상태를 관리하는 오픈 테이블 형식로 정의된다.
- **Apache Hudi**: 타임라인과 파일 그룹으로 업서트•증분 처리를 관리하는 오픈 테이블 형식을 의미한다.

</details>

| 구분 | Apache Iceberg | Delta Lake | Apache Hudi |
|:---|:---|:---|:---|
| 적용 기준 | **다중 엔진•대규모 분석** | 로그 중심 **배치•스트리밍** | **증분 처리•업서트** 중심 |
| 핵심 특징 | **스냅샷•매니페스트 계층** | **순차 로그•체크포인트** | **타임라인•파일 그룹** |
| 한계 | **메타데이터 유지관리** 필요 | 엔진별 **기능 지원 편차** | **테이블 서비스 운영** 복잡 |

#### 한줄 요약

- 세 포맷은 같은 원자 커밋 문제를 상태 자료구조만 달리해 푼 것이며, 매니페스트 트리는 그중 대규모 파일 목록의 조회 비용을 줄이는 쪽에 무게를 둔 **테이블 상태 관리** 방식이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **매니페스트 재작성**: 누적된 작은 매니페스트를 합쳐 계획 단계의 메타데이터 읽기 비용을 줄이는 작업로 정의된다.
- **고아 파일**: 실패한 쓰기 등으로 저장소에 남았지만 어떤 유효 스냅샷도 참조하지 않는 파일을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **작은 파일•매니페스트 누적** | 파일 병합•매니페스트 **재작성 주기** 운영 | **계획•스캔 비용** 감소 |
| **스냅샷•고아 파일 저장비 증가** | 참조 확인 후 **만료•정리** | **저장 비용•삭제 위험** 균형 |
| **엔진별 쓰기•삭제 기능 편차** | 버전별 호환 행렬•**교차 엔진 시험** | **다중 엔진 일관성** 확보 |

#### 한줄 요약

- 파티션 진화 시 **교차 엔진 읽기•동시 커밋 시험**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **파티션 진화**: 기존 데이터를 다시 쓰지 않고 이후 파일에 적용할 파티션 변환 규칙을 변경하는 기능로 정의된다.
- **교차 엔진 시험**: 서로 다른 처리 엔진이 동일 테이블의 읽기•쓰기•삭제를 일관되게 수행하는지 확인하는 시험이다.

</details>

- 특정 벤더 종속 없이 글로벌 빅테크 및 클라우드 DW 진영(Snowflake, BigQuery, Databricks, AWS) 전체의 전폭적인 지지를 받으며 엔터프라이즈 레이크하우스의 실질적 표준으로 확립된 **차세대 개방형 테이블 포맷 및 대규모 분산 메타데이터 관리의 최고 표준(Apache Iceberg / Manifest Tree Metadata Architecture / Hidden Partitioning & Partition Evolution / Multi-Engine Decoupling / REST Catalog Specification)의 확고한 표준**으로 확고히 자리 잡았으며, 오픈 카탈로그(Apache Polaris, Tabular)와 연계된 전사 데이터 거버넌스로 진화하는 가운데, 실무 Apache Iceberg 구축 시에는 **공통 REST 카탈로그를 도입하여 다중 엔진 접근성을 단일화하고, Merge-on-Read(MoR) 삭제 파일로 인한 읽기 지연을 방지하기 위해 백그라운드 컴팩션(Compaction) 및 스냅샷 만료(Expire Snapshots) 주기를 자동화**를 결합하여 완벽한 데이터 신뢰성과 초고속 쿼리 성능을 완성

#### 한줄 요약

- **Iceberg 적용**의 이득은 파일 수가 많고 엔진이 여럿일수록 커지므로, 단일 엔진에 소규모 테이블이라면 메타데이터 운영 비용만 남고 탐색 절감은 체감되지 않는다.
