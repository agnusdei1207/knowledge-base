## 미리 알고가기

- **Apache Iceberg (Apache Iceberg) 오픈 테이블 포맷**: 대규모 분석 환경에서 스냅샷 기반 테이블 관리를 제공함
- **메타데이터 파일**: 메타데이터 파일과 매니페스트 구조로 구성 파일을 추적함
- **멀티엔진 조회**: 엔진 간 일관된 조회와 숨은 파티셔닝을 제공함



## Ⅰ. 개요

Apache Iceberg는 데이터·삭제 파일을 버전별 스냅샷으로 추적하고 스키마·파티션·통계·파일 참조를 계층형 메타데이터로 정의하여 여러 분석 엔진이 일관된 대규모 테이블을 읽고 쓰게 하는 오픈 테이블 포맷임

- **정의/개념**: 스냅샷·매니페스트 기반 오픈 테이블 형식
- **배경/필요성**: 대규모 테이블의 안전한 스키마·파티션 진화

### 쉽게 이해하기 (학습용)

- 창고 폴더를 뒤지지 않고 버전 색인 트리를 통해 상자만 읽어 엔진 공통 테이블을 유지함

## Ⅱ. 특징

- 메타데이터 트리가 커밋 파일을 추적한다.
- 매니페스트 통계가 불필요한 파일을 건너뛴다.
- 필드 ID가 스키마 변경의 안전성을 높인다.
- 숨은 파티셔닝·진화가 재작성 비용을 줄인다.

### 쉽게 이해하기 (학습용)

- 조회자는 날짜 폴더를 외우지 않고 시간 열만 사용하며 Iceberg가 서로 다른 분류법을 자동 변환함

## Ⅲ. 아키텍처 및 구성요소

```text
[Catalog: current metadata pointer]
                 ↓
[Table Metadata: schemas / specs / snapshots]
                 ↓
[Snapshot] → [Manifest List] → [Manifests]
                                      ↓
                         [Data Files / Delete Files]
```

| 설계 요소 | 설명 |
|:---|:---|
| 카탈로그 | 테이블 포인터 관리 및 원자 교체 조건 제공 |
| 테이블 메타데이터 | 스키마, 파티션 명세, 스냅샷 목록 보존 |
| 스냅샷 | 특정 시점 테이블 상태와 매니페스트 연결 |
| 매니페스트 | 데이터·삭제 파일 경로, 통계 불변 기록 |
| 데이터 파일 | 행 수준 데이터 및 삭제 정보 저장 |

> 요약: 메타데이터 트리·통계로 파일 집합을 탐색

### 쉽게 이해하기 (학습용)

- 현재판 색인으로 실제 자료를 찾음, 이전 판본 자료가 있어도 현재판만 참조함

## Ⅳ. 원리 및 절차 흐름도

```text
기준 읽기
    ↓
파일 작성
    ↓
매니페스트 생성
    ↓
메타데이터 생성
    ↓
원자 교체 여부?
    ↓
포인터 교체·공개
```

| 절차 | 설명 |
|:---|:---|
| 기준 읽기 | 카탈로그의 메타데이터와 상태를 고정함 |
| 파일 작성 | 데이터·삭제 파일 및 통계 생성함 |
| 매니페스트 생성 | 변경 사항을 매니페스트에 기록함 |
| 메타데이터 생성 | 새 스냅샷과 메타데이터 파일을 작성함 |
| 원자 교체 | 포인터 비교 후 메타데이터를 교체함 |
| 계획·조회 | 필요한 매니페스트와 파일만 스캔함 |

> 요약: 준비된 불변 파일을 원자적 포인터 교체로 스냅샷 공개함

### 쉽게 이해하기 (학습용)

- 새 판본의 색인을 모두 만든 뒤 현재판 표지만 한 번에 바꾸어 이용자는 갱신 완료된 자료만 봄

## Ⅴ. 종류 및 비교

| 판단 기준 | Iceberg | Hive | 무파티션 |
|:---|:---|:---|:---|
| 핵심 특징 | 파티션 변환식 투영 | 사용자 파티션 열 지정 | 원본 열 전체 스캔 |
| 적용 기준 | 스냅샷 파티션 추적 | 기존 규칙 깨질 수 있음 | 효과 매우 제한적 |
| 주요 위험 | 사양이 자동 보존 | 작성자가 직접 매칭 | 대규모 비용 발생 |

> 요약: 열 변환을 메타데이터로 관리해 질의 단순화

### 쉽게 이해하기 (학습용)

- 이용자는 이름으로 찾고, 시스템이 자동으로 바뀐 분류 규칙을 적용해 상자를 찾음

## Ⅵ. 실무 사례

1. **이벤트 테이블의 파티션 진화**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

2. **배치·스트리밍 엔진의 동시 커밋**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

### 쉽게 이해하기 (학습용)

- 이벤트 테이블의 파티션 진화
- 배치·스트리밍 엔진의 동시 커밋

## Ⅶ. 결론

- 카탈로그 원자성과 엔진 호환성으로 Iceberg 선택

### 쉽게 이해하기 (학습용)

- 색인이 좋아도 표지 안전 교체와 오래된 판본 정리를 하지 않으면 운영 성능이 저하됨
