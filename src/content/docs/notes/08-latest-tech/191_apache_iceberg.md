## 미리 알고가기

- **Apache Iceberg(아파치 아이스버그)**: 대규모 분석 테이블을 스냅샷으로 관리하는 오픈 테이블 형식
- **Manifest(매니페스트)**: 스냅샷이 참조하는 데이터·삭제 파일과 파티션·열 통계를 기록한 메타데이터
- **숨은 파티셔닝(Hidden Partitioning)**: 질의가 물리 파티션 열을 직접 알지 않아도 필터를 자동 변환해 파일을 선별



## Ⅰ. 개요

- 정의/개념: 스냅샷·매니페스트 계층으로 대규모 분석 파일의 테이블 상태를 관리하는 오픈 테이블 형식이다
- 기존 한계: 디렉터리 기반 테이블은 파일 탐색 비용이 크고 파티션·스키마 변경이 질의와 물리 경로에 결합된다
- **배경/필요성**: 다중 엔진에서 안전한 커밋과 스키마·파티션 진화를 지원하기 위함이다

### 쉽게 이해하기 (학습용)

- 디렉터리를 모두 나열하지 않고 스냅샷 색인으로 필요한 파일만 찾는 방식과 같다.

## Ⅱ. 특징

- 스냅샷·매니페스트 계층이 현재 데이터·삭제 파일을 추적한다
- 필드 ID와 파티션 명세로 스키마·파티션 진화를 지원한다
- 매니페스트 통계로 파일을 제거하지만 메타데이터 유지관리가 필요하다

### 쉽게 이해하기 (학습용)

- 사용자는 물리 파티션 열을 몰라도 원본 열 조건으로 필요한 파일을 찾을 수 있다.

## Ⅲ. 아키텍처 및 구성요소

```text
[Catalog: current metadata pointer]
                 ↓
[Table Metadata: schemas / specs / snapshots]
                 ↓
[Snapshot] → [Manifest List] → [Manifests]
                                      ↓
                         [Data Files / Delete Files]
```

| 설계 요소 | 설명 |
|:---|:---|
| 카탈로그 | 테이블 포인터 관리 및 원자 교체 조건 제공 |
| 테이블 메타데이터 | 스키마, 파티션 명세, 스냅샷 목록 보존 |
| 스냅샷 | 특정 시점 테이블 상태와 매니페스트 연결 |
| 매니페스트 | 데이터·삭제 파일 경로, 통계 불변 기록 |
| 데이터 파일 | 행 수준 데이터 및 삭제 정보 저장 |

> 요약: 메타데이터 트리·통계로 파일 집합을 탐색

### 쉽게 이해하기 (학습용)

- 현재 스냅샷의 메타데이터 트리를 따라 유효한 데이터·삭제 파일만 읽는다.

## Ⅳ. 원리 및 절차 흐름도

```text
기준 읽기
    ↓
파일 작성
    ↓
매니페스트 생성
    ↓
메타데이터 생성
    ↓
원자 교체 여부?
    ↓
포인터 교체·공개
```

| 절차 | 설명 |
|:---|:---|
| 기준 읽기 | 카탈로그의 메타데이터와 상태를 고정함 |
| 파일 작성 | 데이터·삭제 파일 및 통계 생성함 |
| 매니페스트 생성 | 변경 사항을 매니페스트에 기록함 |
| 메타데이터 생성 | 새 스냅샷과 메타데이터 파일을 작성함 |
| 원자 교체 | 포인터 비교 후 메타데이터를 교체함 |
| 계획·조회 | 필요한 매니페스트와 파일만 스캔함 |

> 요약: 불변 파일을 준비하고 메타데이터 포인터를 원자적으로 교체한다

### 쉽게 이해하기 (학습용)

- 새 판본의 색인을 모두 만든 뒤 현재판 표지만 한 번에 바꾸어 이용자는 갱신 완료된 자료만 봄

## Ⅴ. 종류 및 비교

| 판단 기준 | Apache Iceberg | Delta Lake | Apache Hudi |
|:---|:---|:---|:---|
| 적용 기준 | 다중 엔진·대규모 분석 | 로그 중심 배치·스트리밍 | 증분 처리·업서트 중심 |
| 핵심 특징 | 스냅샷·매니페스트 계층 | 순차 로그·체크포인트 | 타임라인·파일 그룹 |
| 한계 | 메타데이터 유지관리 필요 | 엔진별 기능 지원 편차 | 테이블 서비스 운영 복잡 |

> 요약: 열 변환을 메타데이터로 관리해 질의 단순화

### 쉽게 이해하기 (학습용)

- 이용자는 이름으로 찾고, 시스템이 자동으로 바뀐 분류 규칙을 적용해 상자를 찾음

## Ⅵ. 실무 사례

1. 이벤트 테이블의 시간 파티션을 일 단위에서 시간 단위로 진화시킨다
2. 배치·스트리밍 엔진의 커밋 충돌을 원자적 포인터 교체로 검증한다

### 쉽게 이해하기 (학습용)

- 이벤트 테이블의 파티션 진화
- 배치·스트리밍 엔진의 동시 커밋

## Ⅶ. 결론

- 다중 엔진 분석은 카탈로그 원자성과 호환성을 확인해 Iceberg를 선택한다

### 쉽게 이해하기 (학습용)

- 카탈로그의 원자적 교체와 스냅샷·작은 파일 유지관리를 함께 수행해야 한다.
