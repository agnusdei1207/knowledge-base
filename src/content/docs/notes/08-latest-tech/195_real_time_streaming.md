## 미리 알고가기

- **실시간 스트리밍 (Real-time Streaming) 연속 이벤트 처리**: 지연을 최소화하여 이벤트 흐름을 처리함
- **시간 기준**: 이벤트 시간과 처리 시간의 차이를 관리하기 위해 워터마크가 중요함
- **정확도**: 상태 관리, 체크포인트, 저장소 연계가 데이터 정확도를 결정함



## Ⅰ. 개요

- 정의/개념: 연속 이벤트를 제한된 지연으로 처리하는 방식
- **배경/필요성**: 이상·장애·설비 변화에 발생 즉시 대응

### 쉽게 이해하기 (학습용)

- 마감 뒤 계산이 아닌 주문 즉시 합계를 갱신하되 늦은 도착과 장애까지 바로잡는 처리임

## Ⅱ. 특징

- event time이 사건 기준 처리를 가능하게 한다.
- window·trigger가 계산 범위와 출력 시점을 정한다.
- watermark가 지연 데이터 처리 기준을 만든다.
- 체크포인트·sink 결속이 중복·누락을 줄인다.

### 쉽게 이해하기 (학습용)

- 주문 시각과 처리 시각은 다르므로 마감선을 정하고, 늦은 영수증은 고칠지 별도 보관할지 정해야 함

## Ⅲ. 아키텍처 및 구성요소

```text
시간 완료(Watermark)
    ↓
구간 결과 출력
    ↓
복구 경계(Checkpoint)
    ↓
소스/상태/저장소
```

| 설계 요소 | 설명 |
|:---|:---|
| 시간 기준 | 이벤트 시간 및 처리 시간 사용 범위 정의 |
| 브로커/로그 | 이벤트 유입 완충 및 재생 가능한 저장 |
| 구간/완료 추정 | 구간 집계와 이벤트 시간 완료 추정 및 지연 허용 |
| 상태/복구 지점 | 키별 누적 상태 및 일관된 복구 지점 저장 |
| 출력 계약 | 결과 반영, 중복 제거 및 장애 처리 계약 |

> 요약: 시간·완료 기준으로 결과와 복구 상태 일치

### 쉽게 이해하기 (학습용)

- 접수함에서 영수증을 꺼내 장부를 만들고, 읽은 위치와 상태, 결과 저장 시점을 함께 기억함

## Ⅳ. 원리 및 절차 흐름도

```text
수신/상태 갱신
    ↓
시간/결과 처리
    ↓
체크포인트
    ↓
장애 시 복구
```

| 절차 | 설명 |
|:---|:---|
| 시간/키 정의 | 이벤트 시각과 분할 키를 부여함 |
| 수집/재생 | 이벤트를 보관하고 재생 위치를 관리함 |
| 시간/상태 연산 | 구간별 상태를 갱신하고 결과를 출력함 |
| 지연 데이터 처리 | 지연 발생 시 수정하거나 폐기함 |
| 복구/출력 | 체크포인트 후 결과에 반영함 |

> 요약: 시간 구간·지연 데이터·복구를 일관 처리

### 쉽게 이해하기 (학습용)

- 마감선이 지나면 결과를 내고, 늦은 주문은 규칙대로 고치며 장애 시 마지막 위치부터 다시 계산함

## Ⅴ. 종류 및 비교

| 판단 기준 | 배치 처리 | 마이크로배치 | 레코드 스트리밍 |
|:---|:---|:---|:---|
| 핵심 특징 | 유한 데이터 단위 | 짧은 시간/건수 단위 | 개별 이벤트 지속 전달 |
| 적용 기준 | 처리 종료 후 산출 | 배치 경계마다 갱신 | 구간/워터마크로 갱신 |
| 주요 위험 | 정산/학습 | 대시보드 | 탐지/제어/상태 연산 |

> 요약: 스트리밍은 단순 반복이 아닌 시간과 상태의 연속적 관리임

### 쉽게 이해하기 (학습용)

- 배치는 일괄 처리, 마이크로배치는 묶음 처리, 스트리밍은 입력마다 장부를 갱신함

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 결제 이상 탐지기는 카드별 5분 event-time window에 금액·지역 상태를 누적하고 watermark 이후 허용 지연 안의 결제는 점수를 수정하며 중복 경보는 거래 ID로 제거함
- 서버 관측 플랫폼은 processing-time 지연 경보와 event-time 서비스 지표를 분리하고 checkpoint 복구 후 재생된 로그가 대시보드 집계를 중복 갱신하지 않게 upsert sink를 사용함

## Ⅶ. 결론

- 지연 이벤트가 포함된 연속 데이터를 정확하게 처리하기 위해 **이벤트 시간·워터마크·상태 크기·중복 처리·복구 보장**을 검토하고, 업무 지연 허용도에 맞는 실시간 스트리밍 정책을 설계해야 한다.

### 쉽게 이해하기 (학습용)

- 빠른 처리뿐 아니라 늦은 기록과 장애 뒤 장부 복구까지 정해야 함
