## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **실시간 스트리밍(Real-Time Streaming)**: 연속 이벤트를 제한된 지연으로 지속 처리하며 시간•상태•복구를 관리하는 데이터 처리 방식을 의미한다.
- **연속 이벤트**: 완료된 유한 집합이 아니라 시간에 따라 끊임없이 도착하는 사건 기록하는 개념로 정의된다.

</details>

- 정의: 연속 이벤트의 시간•상태•복구를 관리하는 **실시간 스트리밍**
- 배경/필요성: 배치 처리는 수집 주기가 끝나야 계산을 시작해 그 주기만큼 판단이 늦어지는 비용을 매번 치르며 **이상 거래•설비 변화 즉시 대응 곤란**을 남기므로, 이벤트가 도착하는 즉시 상태를 갱신하고 늦게 온 데이터만 워터마크로 보정하는 연속 처리 계층의 필요

#### 한줄 요약

- 스트리밍은 판단 시점을 수집 주기에서 이벤트 도착 시점으로 당기는 대신 아직 완결되지 않은 데이터를 다뤄야 하므로, 정확성을 **제한 지연** 안에서 근사하는 구조가 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **이벤트 시간(Event Time)**: 사건이 실제 발생한 시각으로 처리 순서가 아닌 업무 시간 기준 집계에 사용하는 개념이다.
- **워터마크(Watermark)**: 이벤트 시간 진행 정도를 추정해 윈도우 완료와 지연 데이터 처리를 결정하는 기준을 말한다.

</details>

- 실제 사건 발생 시각 기준의 **이벤트 시간** 집계
- 계산 범위•출력 시점을 정하는 **윈도우•트리거**
- 지연 데이터 대기 한계를 판정하는 **워터마크**
#### 한줄 요약

- 워터마크로 **지연 데이터 처리 기준**을 정한다는 것은 언제 결과를 확정할지 스스로 끊는다는 뜻이므로, 기다림을 늘리면 정확해지고 줄이면 빨라지는 조절 손잡이가 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **체크포인트(Checkpoint)**: 장애 복구를 위해 입력 위치와 연산 상태의 일관된 시점을 저장한 복구점을 말한다.
- **상태 연산**: 이벤트 키별 과거 값과 중간 결과를 유지하며 새 입력에 따라 결과를 갱신하는 연산이다.
- **이벤트 로그**: 순서와 위치를 가진 이벤트를 내구성 있게 저장해 재처리 가능한 입력으로 제공하는 정보로 정의된다.
- **윈도우**: 무한 이벤트 흐름을 시간•개수•세션 범위로 나눠 집계하는 연산 단위을 말한다.
- **출력 저장소**: 처리 결과를 후속 서비스•데이터베이스•메시지 주제로 전달하는 목적지을 의미한다.

</details>

```text
              [이벤트 소스•로그]
                       |
                [시간•워터마크]
                       |
               [윈도우•상태 연산]
                   /          \
           [체크포인트]   [출력 저장소]
```

선의 의미: 이벤트 로그와 시간 기준이 상태 연산의 입력을 구성하고, 체크포인트와 출력 저장소가 복구•결과 경계를 제공한다.

| 구성요소 | 책임 |
|:---|:---|
| 이벤트 소스•로그 | 이벤트 유입 완충과 **재생 위치** 관리 |
| 시간•워터마크 | 이벤트 시간 진행과 **허용 지연** 추정 |
| 윈도우•상태 연산 | 구간별 **키 상태•결과** 계산 |
| 체크포인트 | 입력 위치•연산 상태의 **일관된 복구점** 저장 |
| 출력 저장소 | **멱등•트랜잭션 계약** 기반 결과 반영 |

#### 한줄 요약

- 이벤트 로그•상태•체크포인트의 **처리•복구 구조**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멱등 키**: 같은 결과가 반복 출력되어도 저장소에 한 번만 반영되게 식별하는 값을 말한다.
- **허용 지연**: 워터마크 뒤에도 늦게 도착한 이벤트를 집계 수정에 받아들일 시간 범위로 정의된다.

</details>

```text
[이벤트 소스•로그]
       │ 1. 이벤트•발생 시각
       ▼
[시간•워터마크]
       │ 2. 워터마크•윈도우
       ▼
[윈도우•상태 연산]
       ├─ 3. 입력 위치•상태 ──▶ [체크포인트]
       └─ 4. 결과•멱등 키 ────▶ [출력 저장소]

[체크포인트] ── 5. 장애 시 상태 복구 ──▶ [윈도우•상태 연산]
```

### 동작 원리

1. 이벤트•발생 시각: 로그 키와 **이벤트 시간** 제공
2. 워터마크•윈도우: 시간 진행•허용 지연의 **계산 범위** 제공
3. 입력 위치•상태: 복구할 소비 위치와 **키별 상태** 저장
4. 결과•멱등 키: 확정•수정 결과와 **중복 제거 키** 제공
5. 장애 시 상태 복구: **입력 위치•연산 상태** 기반 재실행

#### 한줄 요약

- 워터마크 마감•지연 수정과 **체크포인트 장애 복구**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **마이크로배치**: 짧은 시간이나 건수 단위로 입력을 묶어 반복 실행하는 준실시간 처리 방식로 정의된다.
- **레코드 스트리밍**: 이벤트가 도착할 때마다 연산과 상태를 지속 갱신하는 처리 방식을 말한다.

</details>

| 처리 방식 | 배치 처리 | 마이크로배치 | 레코드 스트리밍 |
|:---|:---|:---|:---|
| 적용 기준 | 정산•학습과 **대규모 일괄 처리** | **준실시간 대시보드** | 탐지•제어와 **상태 연산** |
| 핵심 특징 | **유한 데이터 완료 후 처리** | 짧은 **시간•건수 단위 실행** | **이벤트별 지속 처리** |
| 한계 | **긴 결과 지연** | **배치 경계 지연•부하 진동** | 상태•시간과 **복구 복잡성** |

#### 한줄 요약

- **배치•마이크로배치•스트리밍**은 결과 확정을 얼마나 미룰지의 눈금이며, 확정을 미룰수록 처리 단가는 싸지고 판단 시점은 늦어져 지연 요구가 그대로 선택 기준이 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **키 편향**: 특정 키에 이벤트와 상태가 몰려 일부 처리 노드가 병목이 되는 현상을 말한다.
- **트랜잭션 싱크(Transactional Sink)**: 체크포인트 상태와 출력 커밋을 조정해 복구 후 중복•누락을 억제하는 저장소 연결 방식을 의미한다.
- **유효시간(Time to Live, TTL)**: 상태를 보존한 뒤 자동 만료할 기간로 정의된다.
- **식별자(Identifier, ID)**: 이벤트•거래를 고유하게 구분하는 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **지연•순서 역전 이벤트** | 워터마크•허용 지연과 **수정 정책** | 허용 지연 내 **집계 정확도** 유지 |
| **키 편향•무제한 상태 증가** | 키 재분할•TTL과 **상태 크기 경보** | **처리 병목•저장 폭증** 방지 |
| **복구 후 중복 출력** | 체크포인트•멱등 키와 **트랜잭션 싱크** | **중복•누락** 억제 |

#### 한줄 요약

- 이벤트 시간•허용 지연과 **거래 ID 기반 중복 제거**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **제한 지연**: 업무가 요구하는 최대 시간 안에 이벤트 처리 결과를 제공하는 조건로 정의된다.
- **복구 정합성**: 장애 전 입력 위치•연산 상태•출력 결과를 일관된 시점으로 되돌리는 성질을 의미한다.

</details>

- 초 단위 제어는 **레코드 스트리밍**, 수초•분 허용은 **마이크로배치** 선택

#### 한줄 요약

- **스트리밍 적용**은 지연을 줄이는 대신 상태 관리와 복구 정합성이라는 운영 비용을 새로 지는 선택이므로, 판단이 늦어 생기는 손실이 그 비용을 넘을 때에만 정당화된다.
