## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 메시(Data Mesh)**: 도메인 팀이 데이터 제품의 소유•품질•운영을 책임지고 공통 규칙으로 연결하는 분산 데이터 운영 모델을 의미한다.
- **도메인(Domain)**: 주문•고객처럼 업무 의미와 책임 경계가 같은 영역을 의미한다.

</details>

- 정의: 도메인 팀이 데이터 제품을 책임지는 **데이터 메시 운영 모델**
- 배경/필요성: 중앙 데이터팀이 모든 요청을 처리하면 요청 수만큼 대기가 쌓이는 **처리 병목**에 더해 업무 맥락을 모르는 팀이 품질을 책임지는 **업무 의미•품질 책임 단절**이 남으므로, 데이터를 만든 도메인이 제품으로 소유하고 공통 플랫폼과 전사 규칙이 그 자율을 떠받치도록 책임을 재배치할 필요

#### 한줄 요약

- 데이터 메시는 중앙 병목을 도메인 자율로 푸는 대신 도메인 수만큼 운영 부담을 늘리므로, **공통 플랫폼•전사 규칙 결합**이 그 중복을 흡수하지 못하면 분산이 곧 혼란으로 바뀐다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 제품(Data Product)**: 발견•이해•접근•신뢰•재사용할 수 있도록 계약과 품질 목표를 갖춘 데이터 제공 단위을 말한다.
- **연합 거버넌스**: 도메인 대표와 중앙 조직이 전역 규칙을 합의하고 자동 집행하는 운영 방식이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 데이터 제품이 약속한 신선도•정확성•가용성 목표이다.

</details>

- 도메인 팀의 데이터 의미•품질에 대한 **종단 책임**
- 계약•문서•SLO 기반 **소비자 중심 데이터 제품**
- 셀프서비스 플랫폼•연합 거버넌스 기반 **분산 자율성•상호운용성**
#### 한줄 요약

- 도메인 제품 책임과 **공통 플랫폼•자동 거버넌스**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **셀프서비스 데이터 플랫폼**: 도메인 팀이 파이프라인•저장•관측•정책 기능을 직접 소비하게 하는 공통 기반을 의미한다.
- **카탈로그**: 데이터 제품의 소유자•계약•품질•접근 경로를 발견하도록 제공하는 목록로 정의된다.
- **도메인 소유권**: 데이터를 가장 잘 아는 업무 팀이 데이터의 품질•수명주기•지원 책임을 갖는 원칙을 말한다.
- **연합형 계산 거버넌스**: 전사 공통 규칙과 도메인 자율 규칙을 정책 코드로 조정•자동 집행하는 운영 모델을 말한다.

</details>

```text
                         [연합 거버넌스]
                           /          \
                  [도메인 제품팀]   [셀프서비스 플랫폼]
                           \          /
                          [데이터 제품]
                               |
                       [카탈로그•소비 계층]
```
선의 의미: 연합 거버넌스는 도메인 제품팀과 셀프서비스 플랫폼에 공통 전역 규칙을 제공하고, 도메인 제품팀은 플랫폼의 공통 기능으로 데이터 제품을 소유•운영하며 카탈로그•소비 계층은 그 제품의 발견•접근 경계를 제공한다.

| 구성요소 | 책임 |
|:---|:---|
| 도메인 제품팀 | 데이터 의미•품질과 **운영 책임** 보유 |
| 데이터 제품 | 데이터•코드와 **계약•SLO** 제공 |
| 셀프서비스 플랫폼 | 파이프라인•저장과 **관측 기능** 제공 |
| 카탈로그•소비 계층 | 제품 발견•이해와 **접근 지원** |
| 연합 거버넌스 | **전역 규칙 합의•자동 집행** |

#### 한줄 요약

- 제품팀•플랫폼•거버넌스의 **책임 분리 구조**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **데이터 계약**: 생산자와 소비자가 스키마•의미•품질•변경 호환성을 합의한 규칙로 정의된다.

</details>

```text
[데이터 소비자] ── 사용 목적•품질 요구 ──▶ [도메인 제품팀]
                                                │ 1. 데이터 제품•계약
                                                ▼
                                        [셀프서비스 플랫폼]
                                                │ 2. 정책 검증 결과
                                                ▼
                                         [연합 거버넌스]
                                                │ 3. 승인 제품
                                                ▼
[데이터 소비자] ◀── 제품 정보•접근 경로 ─── [카탈로그]
       └────────── 사용•SLO 피드백 ──────────▶ [도메인 제품팀]
```

### 동작 원리

1. 데이터 제품•계약: 데이터•코드와 **스키마•SLO** 제공
2. 정책 검증 결과: 보안•품질 규칙의 **준수 결과** 제공
3. 승인 제품: 연합 정책을 통과한 **카탈로그 정보** 게시

#### 한줄 요약

- 소비 요구 기반 **제품 계약•정책 검증•카탈로그 게시**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 패브릭**: 활성 메타데이터로 이기종 데이터의 발견•접근•통합•거버넌스를 자동화하는 구조이다.
- **중앙 데이터 플랫폼**: 중앙팀이 여러 도메인의 파이프라인과 데이터 품질을 직접 운영하는 접근법이다.

</details>

| 데이터 운영 접근법 | 데이터 메시 | 데이터 패브릭 | 중앙 데이터 플랫폼 |
|:---|:---|:---|:---|
| 적용 기준 | 다수 도메인의 **책임 분산** | 이기종 자산의 **기술 통합** | 소수 도메인의 **중앙 관리** |
| 핵심 특징 | **도메인 소유•데이터 제품** | 메타데이터 기반 **자동 연결** | **중앙팀 파이프라인 운영** |
| 한계 | **조직 전환•제품 역량** 필요 | **도메인 책임** 별도 설계 | **중앙 병목•의미 단절** |

#### 한줄 요약

- **데이터 메시**와 **데이터 패브릭**은 같은 분산 데이터 문제를 조직 책임과 기술 자동화 중 어디로 풀지의 차이라 배타적이지 않고, 실제로는 메시의 자율을 패브릭의 메타데이터가 떠받치는 조합으로 쓰인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **온콜(On-call)**: 데이터 제품 장애에 대해 정한 시간 안에 대응하는 담당 체계이다.
- **호환성 검사**: 데이터 계약의 버전 변경이 기존 소비자의 처리와 의미를 깨뜨리지 않는지 확인하는 시험을 의미한다.

</details>

데이터 제품별 **SLO•온콜 책임 운영**

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 명목상 소유권과 **운영 책임 불일치** | 제품 소유자•지원 SLO와 **온콜** 명시 | **품질 장애 책임** 확보 |
| 도메인별 **계약•용어 불일치** | 연합 표준•버전 계약과 **호환성 검사** | **제품 조합 가능성** 향상 |
| 플랫폼 역량 부족의 **중복 구현** | 셀프서비스 파이프라인•**관측•정책** 제공 | **도메인 인지 부하** 감소 |

#### 한줄 요약

- 도메인의 계약•SLO 소유와 **플랫폼 발견•권한•관측** 제공

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **종단 책임**: 도메인 팀이 데이터 생성부터 품질•지원•폐기까지 제품 수명주기 전체를 맡는 원칙이다.
- **제품 역량**: 데이터를 소비자 요구•계약•SLO•지원 체계가 있는 지속 운영 제품으로 관리하는 능력을 말한다.

</details>

- 도메인이 수명주기•SLO를 운영하면 **데이터 메시**, 아니면 **중앙 플랫폼** 선택

#### 한줄 요약

- **데이터 메시 적용**은 기술 도입이 아니라 소유권 이전이므로, 도메인이 계약과 SLO를 실제로 책임질 준비가 없으면 중앙 병목이 도메인별 방치로 바뀔 뿐이다.
