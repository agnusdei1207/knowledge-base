## 미리 알고가기

- **프롬프트 튜닝 (Prompt Tuning, PT)**: 가상 토큰 임베딩만 학습
- **소프트 프롬프트 (Soft Prompt)**: 학습 가능한 연속 벡터 토큰
- **하드 프롬프트 (Hard Prompt)**: 자연어 지시문
- **PEFT (Parameter-Efficient Fine-Tuning, PEFT)**: 일부 매개변수만 학습


## Ⅰ. 개요

- **정의/개념**: 입력 앞의 소프트 프롬프트 임베딩만 학습
- **배경/필요성**: 과제별 적응 비용과 모델 복제 부담 절감

### 쉽게 이해하기 (학습용)

- 입력에 가상 토큰을 붙이고 원하는 출력에 맞춰 그 값만 최적화합니다.

## Ⅱ. 특징

- 소프트 프롬프트는 실제 토큰 임베딩 앞에 결합된다.
- 기반 모델은 동결하고 과제별 가상 토큰만 학습한다.
- 가상 토큰 수만큼 문맥 사용량과 계산량이 늘어난다.
- 성능은 모델 규모·과제·초기화에 따라 달라진다.

### 쉽게 이해하기 (학습용)

- 학습은 가볍지만 기반 모델과 과제의 적합성은 따로 검증해야 합니다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 소프트 프롬프트 | 학습 가능한 연속 임베딩 벡터 |
| 프롬프트 길이 | 가상 토큰 수·문맥 연산량 |
| 임베딩 결합기 | 가상·실제 토큰 연결 |
| 동결 백본 | 모델 가중치 고정·입력 처리 |
| 과제 손실 | 소프트 프롬프트 갱신 그래디언트 |

```text
가상토큰 ─── 입력결합 ─── 동결모델 ─── 과제출력
실제토큰 ─┘
```

### 쉽게 이해하기 (학습용)

- 가상 토큰과 실제 토큰을 묶고 가상 토큰만 학습합니다.

## Ⅳ. 원리 및 절차 흐름도

```text
토큰초기
↓
입력결합
↓
모델추론
↓
선택갱신
↓
과제배포
```

| 절차 | 설명 |
|:---|:---|
| 토큰초기 | 가상 토큰 길이·차원 초기화 |
| 입력결합 | 가상·실제 토큰 연결 |
| 모델추론 | 동결 모델 과제 출력 생성 |
| 선택갱신 | 가상 토큰만 그래디언트 갱신 |
| 과제배포 | 프롬프트 분리 저장 및 적재 |

### 쉽게 이해하기 (학습용)

- 가상 토큰만 갱신해 과제별로 분리해 저장합니다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 하드 프롬프트 | 프롬프트 튜닝 | 접두어 튜닝 |
|:---|:---|:---|:---|
| 조정 대상 | 자연어 지시문 | 입력층 가상 토큰 | 계층별 키·값 접두어 |
| 추론 비용 | 지시문 토큰 연산 | 가상 토큰 연산 | 계층별 캐시 연산 |
| 적용 기준 | 즉시 수정 필요 시 | 입력층 조정 시 충분 시 | 계층별 제어 필요 시 |

> 요약: 방식별 조정 대상과 추론 비용 비교

### 쉽게 이해하기 (학습용)

- 하드·소프트·접두어 방식은 조정 위치와 비용이 다릅니다.

## Ⅵ. 실무 사례

- 과제별 소프트 프롬프트 적재 및 전면 튜닝 대비 품질 확인
- 프롬프트 길이·문맥 한도·응답 지연 측정

### 쉽게 이해하기 (학습용)

- 공용 모델의 과제별 가상 토큰이 문맥을 과도하게 차지하지 않는지 검증합니다.

## Ⅶ. 결론

- 프롬프트 튜닝은 품질·문맥·추론 비용을 함께 잰다.

### 쉽게 이해하기 (학습용)

- 기반 모델이나 과제가 달라지면 품질과 문맥 비용을 다시 확인해야 합니다.
