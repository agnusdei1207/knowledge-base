## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프롬프트 튜닝(Prompt Tuning)**: 동결 모델의 입력 앞에 붙는 과업별 가상 토큰 벡터만 학습하는 매개변수 효율적 파인튜닝 기법.
- **소프트 프롬프트(Soft Prompt)**: 사람이 읽는 문장이 아니라 역전파로 값이 갱신되는 연속 임베딩 벡터이다.

</details>

- 정의: 동결 모델 입력의 가상 토큰만 학습하는 **프롬프트 튜닝**이다.
- 배경/필요성: 전체•어댑터 튜닝의 **업무별 가중치•모듈 관리 비용** #### 한줄 요약
- 동결 모델 앞의 **과업별 가상 토큰** 한정 학습

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가상 토큰(Virtual Token)**: 실제 어휘 식별자가 아니라 학습 가능한 임베딩으로 입력 앞에 결합되는 과업 표현.
- **동결 백본(Frozen Backbone)**: 학습 중 가중치를 유지하며 소프트 프롬프트가 조건화한 출력을 생성하는 기반 모델로 정의된다.
- **문맥 비용(Context Cost)**: 가상 토큰이 컨텍스트 윈도우를 차지하여 실제 입력과 출력에 쓸 공간을 줄이는 비용을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

- **연속 임베딩**: 실제 입력 앞에 학습 벡터 결합
- **선택 갱신**: 기반 모델 동결과 가상 토큰 학습
- **표현 용량•문맥 비용**: 프롬프트 길이에 따른 절충

#### 한줄 요약
- **표현 용량•문맥 비용** 사이에서 길이 절충

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **프롬프트 초기화기(Prompt Initializer)**: 가상 토큰의 길이•차원과 초기 임베딩 값을 구성하는 모듈을 나타낸다.
- **임베딩 결합기(Embedding Concatenator)**: 소프트 프롬프트와 실제 토큰 임베딩을 하나의 입력 시퀀스로 연결하는 역할을 담당한다.
- **과업 손실기(Task Loss Calculator)**: 모델 출력과 정답의 차이로 소프트 프롬프트에 적용할 그래디언트를 산출함을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

```text
                 [소프트 프롬프트]
                         |
                [프롬프트 초기화기]
                         |
                  [임베딩 결합기]
                         |
                    [동결 백본]
                         |
                   [과업 손실기]
```

선의 의미: 소프트 프롬프트와 초기화기가 학습 입력을 정의하고, 임베딩 결합기와 동결 백본 및 과업 손실기가 선택 갱신 경계를 구성함.

| 구성요소 | 책임 |
|:---|:---|
| 소프트 프롬프트 | **과업별 연속 임베딩** 저장 |
| 프롬프트 초기화기 | **가상 토큰 길이•차원** 초기값 구성 |
| 임베딩 결합기 | **가상•실제 토큰 입력** 연결 |
| 동결 백본 | 고정 가중치 기반 **과업 출력** 생성 |
| 과업 손실기 | **소프트 프롬프트 그래디언트** 산출 |

#### 한줄 요약
- **소프트 프롬프트•초기화•결합•백본•손실** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **선택 역전파(Selective Backpropagation)**: 기반 모델은 동결하고 가상 토큰 임베딩에만 손실 그래디언트를 적용하는 과정으로 정의된다.
- **과업별 자산(Task-specific Asset)**: 업무별로 분리 저장하고 실행 시 선택 적재하는 작은 소프트 프롬프트 벡터를 가리킨다.

</details>

```text
구성•소프트 프롬프트
       │ 1. 가상 토큰 길이•차원 초기화
       ▼
┌──────────── 학습 종료 전 반복 ────────────┐
│ 소프트 프롬프트                           │
│   │ 2. 가상•실제 임베딩 결합              │
│   ▼                                       │
│ 동결 백본                                 │
│   │ 3. 동결 모델 과업 출력                │
│   ▼                                       │
│ 과업 손실기                               │
│   └ 4. 가상 토큰만 갱신                  │
└───────────────────────────────────────────┘
       │ 5. 과업별 프롬프트 저장•적재
       ▼
실행 관리자
```

### 동작 원리

1. 가상 토큰 길이•차원 초기화: 모델 임베딩 차원과 과업에 맞는 **학습 벡터** 활용 생성함.
2. 가상•실제 임베딩 결합: 소프트 프롬프트를 입력 앞에 붙여 **통합 시퀀스** 활용 구성함.
3. 동결 모델 과업 출력: 기반 가중치를 유지한 채 결합 입력의 **예측 결과** 활용 생성함.
4. 가상 토큰만 갱신: 과업 손실의 그래디언트를 소프트 프롬프트에만 **역전파**함.
5. 과업별 프롬프트 저장•적재: 작은 벡터 자산을 분리해 **업무별 실행 경로** 활용 전환함.

#### 한줄 요약
- **초기화•결합•출력•가상 토큰 갱신•저장** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하드 프롬프트(Hard Prompt)**: 사람이 읽고 직접 작성•수정하는 자연어 지시문이다.
- **프롬프트 튜닝 적용(Prompt Tuning Adaptation)**: 입력층에 학습 가능한 가상 토큰을 붙여 과업 행동을 조정함.
- **접두어 튜닝(Prefix Tuning)**: 모델 각 층의 키(Key, K)•값(Value, V) 앞에 학습 가능한 접두어 벡터를 붙여 계층별 문맥을 제어하는 기법을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

- 입력층 조정은 **Prompt Tuning**, 계층별 K•V 제어는 **Prefix Tuning** | 구분 | 하드 프롬프트 | Prompt Tuning | Prefix Tuning |
|:---|:---|:---|:---|
| 적용 기준 | 즉시 **작성**•**해석** 필요 | **입력층 조정** 기반 충분 | 계층별 **문맥 제어** 필요 |
| 핵심 특징 | **자연어 지시문** 직접 작성 | 입력층 **가상 토큰 학습** | 계층별 **키•값 접두어 학습** |
| 한계 | 작성자•**표현 편차** | 문맥 점유•**해석 곤란** | 계층별 **캐시 메모리** 증가 |

#### 한줄 요약
- **조정 위치•해석성•문맥 비용** 기반 방식 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표현 부족(Insufficient Expression)**: 가상 토큰이 너무 짧아 과업 정보를 충분히 담지 못하는 문제를 나타낸다.
- **문맥 윈도우(Context Window)**: 모델이 한 번의 추론에서 참조할 수 있는 입력•출력 토큰의 최대 범위.
- **모델 호환 실패(Model Incompatibility)**: 기반 모델을 교체하면 임베딩 공간이 달라 기존 소프트 프롬프트의 품질이 낮아지는 현상으로 정의된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 짧은 가상 토큰의 **과업 표현 부족** | **길이별 품질•문맥 점유 비교** | 최소 유효 **토큰 길이 선택** |
| 긴 가상 토큰의 **입력 문맥 축소** | **출력 예약•입력 예산 분리** | 문맥 윈도우 **초과 방지** |
| 기반 모델 교체의 **프롬프트 호환 실패** | **모델별 재학습•회귀 시험** | 과업 품질 **복원** |

#### 한줄 요약
- **표현 용량•문맥 점유•모델 호환성** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **프롬프트 길이 선택(Prompt Length Selection)**: 과업 품질을 충족하는 최소 토큰 수와 실제 입력•출력 예산을 함께 비교해 결정하는 과정을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **적응 방식 선택(Adaptation Method Selection)**: 입력층 조정으로 충분하면 프롬프트 튜닝, 계층별 문맥 제어가 필요하면 접두어 튜닝을 적용함이다.

</details>

- 입력층 조정은 **Prompt Tuning**, 계층별 문맥 제어는 **Prefix Tuning** 선택

#### 한줄 요약
- **조정 위치•문맥 예산** 기반 튜닝 방식 결정
