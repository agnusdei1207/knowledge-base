## 미리 알고가기

- **가상 스레드(Virtual Thread)**: '버추얼 스레드'로 읽으며, JDK가 관리하는 경량 Java 스레드
- **자바 개발 키트(Java Development Kit, JDK)**: '제이디케이'로 읽으며, Java 개발·실행 도구와 라이브러리 집합
- **자바 가상 머신(Java Virtual Machine, JVM)**: '제이브이엠'으로 읽으며, Java 바이트코드를 실행하는 가상 머신
- **운영체제(Operating System, OS)**: '오에스'로 읽으며, 플랫폼 스레드가 사용하는 실행 자원을 관리
- **입출력(Input/Output, I/O)**: '아이오'로 읽으며, 네트워크·파일·DB 응답을 기다리는 작업
- **JFR(Java Flight Recorder)**: '제이에프알'로 읽으며, Java 실행 이벤트와 성능 문제를 기록하는 도구

## Ⅰ. 개요

- 정의/개념: 다수의 작업을 소수의 운반자 플랫폼 스레드에 대응시키는 **JDK 관리 경량 Thread**
- **배경/필요성**: 요청별 플랫폼 스레드 방식의 **OS 스레드 수와 메모리 한계를 완화**하기 위해 필요

### 쉽게 이해하기 (학습용)

- 대기 중인 상담 기록은 내려놓고 실제 상담 직원이 다른 업무를 처리하게 해, 적은 직원으로 많은 대기 요청을 다루는 방식이다.

## Ⅱ. 특징

- 작업마다 가상 스레드를 만들고 JDK 스케줄러가 **운반자 스레드에 마운트·언마운트**한다.
- 지원되는 블로킹 I/O에서는 운반자를 반환하며, Java 24부터 `synchronized` 구간도 대부분 고정되지 않는다.
- I/O 대기 동시성을 높이지만 **CPU 연산 속도와 DB 연결 같은 외부 자원 용량은 늘리지 않는다**.

### 쉽게 이해하기 (학습용)

- 기다리는 요청은 실제 스레드를 양보하지만 계산 중인 요청과 DB 연결 수는 별도로 제한해야 한다.

## Ⅲ. 구성요소 및 구조

```text
가상 스레드 → JDK 스케줄러 → 운반자 스레드 → CPU
                  ↑↓ 마운트·언마운트
                    I/O 대기
```

| 설계 요소 | 설명 |
|:---|:---|
| 가상 스레드 | **작업별 실행 상태 보존** |
| JDK 스케줄러 | **운반자 배정·분리 관리** |
| 운반자 스레드 | **OS 플랫폼 스레드로 실제 실행** |
| 블로킹 I/O | **대기 중 운반자 반환 유도** |
| 외부 자원 제한 | **DB·CPU·메모리 동시성 통제** |

> 요약: JDK가 가상 스레드를 운반자에 올려 실행하고 I/O 대기 중 분리한다.

### 쉽게 이해하기 (학습용)

- 배정 담당자가 많은 상담 기록을 몇 개의 실제 책상에 번갈아 올리는 구조다.

## Ⅳ. 원리 및 절차 흐름도

```text
작업 생성 → Mount·실행 → 대기 분기 → Unmount·재개 → 완료·관측
```

| 절차 | 설명 |
|:---|:---|
| 작업 생성 | 요청마다 가상 스레드 시작 |
| Mount·실행 | 운반자 스레드에 올려 실행 |
| 대기 분기 | I/O 대기와 고정 구간 판별 |
| Unmount·재개 | 운반자 반환 후 작업 재개 |
| 완료·관측 | 처리량·고정·자원 포화 확인 |

> 요약: 작업별 가상 스레드는 I/O 대기에 운반자를 반환하고 준비되면 다시 실행된다.

### 쉽게 이해하기 (학습용)

- 응답을 기다리는 기록은 책상에서 치웠다가 답이 오면 다시 올리고, 고정 구간과 자원 포화를 관측한다.

## Ⅴ. 종류 및 비교

| Java 동시성 실행 모델 | 가상 스레드 | 플랫폼 스레드 | 비동기 이벤트 루프 |
|:---|:---|:---|:---|
| 적용 기준 | 독립적인 블로킹 I/O 다수 | CPU 작업·제한된 동시성 | 전 구간 비차단 처리 |
| 핵심 특징 | JDK의 다대소수 운반자 대응 | Java·OS 스레드 대응 | 소수 스레드의 이벤트 순환 |
| 한계 | CPU·외부 자원 용량은 동일 | 대기 중 OS 스레드 점유 | 콜백·반응형 구성 복잡 |

> 요약: 블로킹 I/O 동시성에는 가상 스레드, 제한 작업에는 플랫폼 스레드, 비차단 흐름에는 이벤트 루프가 적합하다.

### 쉽게 이해하기 (학습용)

- 많은 대기 기록을 번갈아 처리할지, 직원이 하나씩 전담할지, 준비된 일만 순환 처리할지 선택하는 차이다.

## Ⅵ. 실무 사례

1. **DB·HTTP 대기 요청 서버의 요청별 가상 스레드**
2. **CPU·네이티브 작업 분리와 JFR 고정 관측**

### 쉽게 이해하기 (학습용)

- 대기 요청은 가상 스레드로 처리하되 DB 연결 수와 처리량을 함께 제한한다.
- CPU 작업은 코어 수에 맞춰 분리하고, 네이티브 호출의 고정 현상은 JFR로 확인한다.

## Ⅶ. 결론

- 가상 스레드는 **블로킹 I/O 동시성 확장 수단**이며, CPU 가속이나 외부 자원 증설 수단이 아니다.

### 쉽게 이해하기 (학습용)

- 가벼운 요청 기록을 많이 만들 수 있어도 CPU와 DB 창구 수는 늘지 않는다.
