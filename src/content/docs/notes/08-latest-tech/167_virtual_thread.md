## 미리 알고가기

- **Virtual Thread**: OS 스레드보다 가벼운 사용자 수준 스레드
- **동기식 코드**: 동기식 코드로 높은 동시성을 확보함
- **스케줄링**: JVM이 carrier 스레드로 실행함



## Ⅰ. 개요

- **정의/개념**: JVM이 스케줄링하는 경량 스레드
- **배경/필요성**: 동기 코드의 대규모 대기 작업 처리

### 쉽게 이해하기 (학습용)

- 상담 업무마다 직원을 한 명씩 고용하는 대신 상담 기록을 가볍게 만들고, 실제 직원은 고객의 답을 기다리는 기록을 내려놓고 다른 상담을 처리하는 방식임

## Ⅱ. 특징

- 작업마다 가상 스레드를 만들고 풀링하지 않는다
- 가상 스레드는 플랫폼 스레드에 마운트돼 실행된다
- 블로킹 I/O 때 언마운트돼 플랫폼 스레드를 돌려준다
- 대기 동시성은 높이나 CPU 계산은 빨라지지 않는다

### 쉽게 이해하기 (학습용)

- 기다리는 상담 기록은 책상에서 치우고 다른 기록을 올릴 수 있지만, 실제 계산을 계속 해야 하는 상담은 직원 수보다 많이 펼쳐도 더 빨라지지 않음

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 가상 스레드 | 실행 상태를 보존하는 단위 |
| JDK 스케줄러 | carrier에 배정하고 관리함 |
| Carrier 스레드 | 실제 OS 스레드 실행 |
| 블로킹 I/O | 대기 시 스레드 분리 |
| 관측/제한 | 외부 자원 동시성 관리 |

```text
가상스레드 → 스케줄러 → carrier → CPU
               ↑↓ unmount
              블로킹
```

> 요약: 가상 스레드를 carrier에 배정·분리한다.

### 쉽게 이해하기 (학습용)

- 수많은 상담 기록을 배정 담당자가 몇 개의 실제 책상에 올리고, 답을 기다리는 기록은 보관대에 두어 책상을 비우는 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
생성 → carrier 배치
          ↓
      대기발생
    ┌────┴────┐
  I/O      native
   ↓         ↓
분리반환   고정대기
   └────┬────┘
        ↓
     코드재개
```

| 절차 | 설명 |
|:---|:---|
| 작업 생성 | 요청마다 새 가상 스레드를 시작하고 풀을 미사용함 |
| Mount·실행 | 가상 스레드를 carrier에 올려 실행함 |
| 대기 분기 | I/O가 carrier를 고정하는지 판별함 |
| Unmount·재개 | I/O 대기 때 carrier를 반환함 |
| 완료·관측 | 결과를 반환하고 pinning·처리량·외부 자원 포화를 관측함 |

> 요약: 작업별 스레드가 I/O 대기에 carrier를 돌려준다.

### 쉽게 이해하기 (학습용)

- 기다리는 전화는 기록을 내려놓아 책상을 비우지만, 책상에서만 할 수 있는 특수 작업은 끝날 때까지 직원을 붙잡으므로 이런 구간을 찾아야 함

## Ⅴ. 종류 및 비교

| 판단 기준 | 가상 스레드 | 플랫폼 스레드 | 비동기 이벤트 루프 |
|:---|:---|:---|:---|
| 스케줄링·자원 | JVM이 다수 작업을 carrier 플랫폼 스레드에 배치함 | Java 스레드가 OS 스레드와 연결되어 실행됨 | 소수 스레드가 준비된 이벤트를 순환 처리함 |
| 블로킹·코드 모델 | 지원 I/O에서 carrier를 반납함 | 블로킹 동안 연결된 OS 스레드를 점유함 | 비차단 API와 콜백·단계 조합이 필요함 |
| 적용 경계 | 많은 독립 I/O 대기 작업 | CPU 작업·native 고정은 별도 제한함 | 비차단 전 구간과 흐름 제어가 준비된 파이프라인 |

> 요약: I/O는 가상, CPU는 플랫폼, 비차단은 루프다.

### 쉽게 이해하기 (학습용)

- 상담 기록을 실제 직원에게 번갈아 맡기면 가상 스레드, 직원 한 명이 기록 하나를 끝까지 잡으면 플랫폼 스레드, 접수 알림이 온 일만 순서대로 처리하면 이벤트 루프임

## Ⅵ. 실무 사례

1. DB·외부 HTTP 응답을 주로 기다리는 요청 서버는 요청마다 가상 스레드를 만들고 처리량·대기열·DB 연결 수를 함께 제한함
2. 이미지 인코딩 같은 CPU-bound 작업은 코어 수에 맞춘 제한 실행기로 분리하고 native 라이브러리 구간은 JFR로 pinning을 점검함

### 쉽게 이해하기 (학습용)

- 응답을 기다리는 고객 상담은 기록을 많이 만들되 DB 창구 수는 제한하고, 계속 계산하는 영상 작업은 CPU 수만큼만 배정해야 함

## Ⅶ. 결론

- I/O 대기에 쓰고 CPU 계산 가속에는 쓰지 않는다

### 쉽게 이해하기 (학습용)

- 가벼운 상담 기록을 많이 만들 수 있어도 실제 직원과 DB 창구와 CPU는 늘지 않으므로 기다림이 많은 업무에 맞춰 써야 함
