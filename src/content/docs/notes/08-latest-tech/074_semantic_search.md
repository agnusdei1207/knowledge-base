## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **의미 검색**: 질의와 문서를 벡터화해 표현이 달라도 의미가 가까운 후보를 찾는 검색 방식이다.
- **밀집 검색**: 임베딩 공간에서 벡터 거리를 기준으로 관련 문서를 찾는 방식이다.

</details>

- 정의/개념: 질의·문서를 벡터화해 의미가 가까운 후보를 찾는 **밀집 검색 방식**
- 배경/필요성: 어휘 일치 검색은 **동의어·다른 표현**의 문서 누락

#### 한줄 요약

- 표현이 달라도 뜻이 비슷한 질문과 문서를 같은 벡터 공간에서 찾습니다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **임베딩**: 질의나 문서의 의미 특징을 계산 가능한 고차원 벡터로 변환한 표현이다.
- **근사 최근접 이웃(ANN)**: 전체 벡터를 정확히 비교하는 대신 가까운 후보를 빠르게 찾는 색인 기법이다.

</details>

- 질의와 문서를 함께 표현하는 **공동 의미 벡터 공간**
- 의미상 가까운 후보를 찾는 **벡터 유사도·ANN 색인**
- 도메인·식별자 누락을 보정하는 **희소·정확 검색 보완**

#### 한줄 요약

- 낯선 전문 분야나 제품 번호는 의미 검색이 빗나갈 수 있어 정확 검색도 필요합니다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **표현 모델**: 질의와 문서를 같은 의미 벡터 공간으로 변환하는 모델이다.
- **유사도 함수**: 질의 벡터와 문서 벡터가 의미상 가까운 정도를 계산한다.
- **메타데이터 필터**: 권한·기간·문서 유형 같은 조건으로 검색 후보를 제한한다.

</details>

```mermaid
block-beta
  columns 3
  encoder["표현 모델"]
  index["의미 색인"]
  similarity["관련성 함수"]
  lexical["문자열 경로"]
  metadata["메타데이터"]
  encoder --- index
  index --- similarity
  similarity --- lexical
  lexical --- metadata
```

| 구성요소 | 책임 |
|:---|:---|
| **표현 모델** | 질의·문서를 의미 벡터로 변환 |
| **의미 색인** | 문서 벡터·식별자 관계 저장 |
| **관련성 함수** | 질의·문서 의미 유사도 계산 |
| **문자열 경로** | 코드·식별자 정확 후보 보완 |
| **메타데이터** | 조건 필터로 부적합 후보 제외 |


#### 한줄 요약

- 의미 후보에 정확 문자열과 권한 조건을 함께 적용합니다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **벡터 색인**: 문서 임베딩을 저장하고 가까운 벡터를 효율적으로 조회하도록 만든 구조이다.
- **후보 회수율**: 실제 관련 문서 가운데 ANN 검색 후보에 포함된 문서의 비율이다.

</details>

```mermaid
sequenceDiagram
  participant E as 표현 모델
  participant I as 의미 색인
  participant S as 관련성 함수
  participant F as 메타데이터
  E->>I: 1. 문서 벡터 저장
  E->>I: 2. 질의 벡터 탐색
  I->>S: 3. 근사 이웃 후보 전달
  S->>F: 4. 유사도 순위·조건 필터
  F-->>E: 허용 문서 순위 반환
```

**동작 원리**

1. **문서 벡터 저장**: 문서 의미를 **동일 벡터 공간**에 배치
2. **질의 벡터 탐색**: 질의 의도를 **임베딩 벡터**로 변환
3. **근사 이웃 후보 전달**: ANN으로 **탐색 범위** 축소
4. **유사도 순위·조건 필터**: 의미 거리와 **메타데이터 조건** 결합

#### 한줄 요약

- 의미 후보를 찾고 정확 문자열과 권한 조건으로 보완합니다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **정확 검색**: 문자나 식별자의 완전·부분 일치를 기준으로 문서를 찾는 방식이다.
- **희소 검색**: 단어 빈도와 희귀도 같은 어휘 신호를 사용해 문서를 찾는 방식이다.

</details>

| 검색 방식 | 의미 검색 | 정확 검색 | 희소 검색 |
|:---|:---|:---|:---|
| **적용 기준** | 표현보다 **의미** 중요 | **식별자 표기** 중요 | **핵심 용어** 출현 |
| **핵심 특징** | 임베딩 **의미 유사도** | 문자열 **완전·부분 일치** | 어휘 **빈도·희귀도** |
| **한계** | 도메인 **거리 왜곡** | 표기 **변형 누락** | 동의어·**의도 누락** |

#### 한줄 요약

- 문자열·희소·밀집 검색은 관련성을 판단하는 기준이 다릅니다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **도메인 불일치**: 임베딩 모델의 학습 분야와 실제 문서 분야가 달라 의미 거리가 왜곡되는 문제이다.
- **식별자 누락**: 코드나 고유명사의 정확한 문자열 신호를 의미 검색이 놓치는 문제이다.
- **과도한 탐색 축소**: ANN 설정이 후보 범위를 지나치게 줄여 관련 문서를 제외하는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 도메인의 **임베딩 불일치** | 도메인 평가셋으로 **표현 모델** 선택 | 의미 **거리 왜곡 감소** |
| 고유명사·**코드 누락** | **정확·희소 검색** 후보 결합 | **식별자 회수** 보완 |
| ANN의 **탐색 축소 과다** | 탐색 폭과 **회수율·지연** 실측 | 이웃 **누락 통제** |

#### 한줄 요약

- 자연어 질문은 의미로 찾고 오류 코드는 정확히 일치시키며 도메인별 성능을 검증합니다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **도메인 평가셋**: 실제 업무 질의와 정답 문서로 의미 검색 성능을 검증하는 자료 집합이다.
- **하이브리드 보완**: 의미 검색에 정확·희소 검색을 결합해 고유명사와 식별자 회수를 높이는 방법이다.

</details>

- **도메인 의미 유사성**이 핵심인 질의에 의미 검색을 적용하고 **정확 검색**으로 식별자 보완

#### 한줄 요약

- 코드·전문용어는 정확 검색으로 보완하고 새 도메인마다 회수 성능을 확인해야 합니다.
