## 미리 알고가기

- **FaaS(함수 단위 서버리스 실행)**: 이벤트 기반 함수 단위 코드 실행
- **적합 워크로드**: 짧은 무상태 처리에 적합하며 장기 세션에는 부적합
- **서버리스**: 서버리스의 하위 함수 실행 모델임



## Ⅰ. 개요

- **정의/개념**: 이벤트별 함수를 자동 실행·확장
- **배경/필요성**: 간헐 작업의 유휴 자원·운영 부담 감소

### 쉽게 이해하기 (학습용)

- FaaS는 주문마다 필요한 작업만 시켜 끝나면 돌려보내는 방식이다.

## Ⅱ. 특징

- 이벤트가 격리 실행 환경의 함수 입력을 만든다
- 플랫폼 회수로 인스턴스 지속을 가정할 수 없다
- 영속 상태·중복 키는 외부 저장소에 둔다
- 실행 시간·메모리 한도는 장시간 작업을 제한한다
- 새 환경 초기화가 첫 호출 지연을 늘린다

### 쉽게 이해하기 (학습용)

- 첫 호출은 작업 공간을 준비해 느리지만 재사용하면 준비 시간이 줄어든다.

## Ⅲ. 아키텍처 및 구성요소

```text
[이벤트] → [트리거] → [실행 환경]
                         ↓
                  [함수] ↔ [외부 상태]
```

| 설계 요소 | 설명 |
|:---|:---|
| 이벤트 소스 | 함수 실행 이벤트 생성 |
| 트리거·바인딩 | 이벤트와 대상 함수 연결 |
| 실행 플랫폼 | 환경 생성·재사용·회수 |
| 함수 핸들러 | 단일 책임 로직 수행 |
| 외부 상태 | 영속 상태·멱등 키 저장 |

> 요약: 이벤트·실행 환경·외부 상태를 연결한다

### 쉽게 이해하기 (학습용)

- 실행 공간은 사라질 수 있어 중요한 기록은 외부 장부에 남겨야 한다.

## Ⅳ. 원리 및 절차 흐름도

```text
이벤트수신
    ↓
환경확인
    ↓
함수실행
    ↓
상태반영
    ↓
완료처리
```

| 절차 | 설명 |
|:---|:---|
| 이벤트 수신 | 이벤트·호출 식별자 확보 |
| 트리거 적용 | 함수·동시성·재시도 확인 |
| 환경 준비 | 환경 초기화 또는 재사용 |
| 함수 호출 | 제한 시간 안에 로직 수행 |
| 상태 반영 | 결과·멱등 키 원자적 기록 |
| 완료 처리 | 확인·재시도·실패 큐 분기 |

> 요약: 환경을 준비해 실행하고 결과를 외부에 기록한다

### 쉽게 이해하기 (학습용)

- 주문 번호를 외부에서 확인해 같은 작업이 두 번 실행되지 않게 한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | FaaS | 서버리스 컨테이너 | 상시 실행 서비스 |
|:---|:---|:---|:---|
| 호출·수명 | 이벤트별 단기 함수 | 요청별 컨테이너 유지 | 상시 프로세스 실행 |
| 상태·제어 | 외부 상태·제한된 제어 | 이미지·연결 수명 제어 | 상태·자원 직접 제어 |
| 적용 기준 | 간헐적 독립 이벤트 | 긴 요청·사용자 런타임 | 지속 트래픽·장기 연결 |

> 요약: 실행 수명·상태·제어 범위로 모델을 고른다

### 쉽게 이해하기 (학습용)

- 짧은 일은 함수, 긴 일은 컨테이너, 지속 업무는 상시 서비스가 알맞다.

## Ⅵ. 실무 사례

1. 객체 이벤트로 썸네일 함수를 실행한다
2. 웹훅은 준비 환경과 큐로 지연을 낮춘다

### 쉽게 이해하기 (학습용)

- 이미지 키를 멱등 키로 써 중복 변환을 막고 실패는 큐로 보낸다.
- 지연 민감 웹훅은 환경을 미리 준비하고 후속 작업을 큐로 넘긴다.

## Ⅶ. 결론

- 짧은 무상태 작업과 하류 용량에 맞춰 FaaS를 적용한다.

### 쉽게 이해하기 (학습용)

- 함수 수만 늘리지 말고 저장소와 API가 감당할 만큼만 작업을 보낸다.
