## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **서비스형 함수(Function as a Service, FaaS)**: 이벤트에 따라 함수 단위 코드를 격리 환경에서 실행하고 자동 확장하는 클라우드 서비스이다.
- **서버리스 컴퓨팅**: 인프라 준비·확장·회수를 공급자가 담당하는 클라우드 운영 모델이다.

</details>

- 정의/개념: **서비스형 함수(Function as a Service, FaaS)** 는 이벤트에 따라 함수 단위 코드를 격리 환경에서 실행하고 요청량에 맞춰 자동 확장·계량하는 서버리스 클라우드 서비스
- 배경/필요성: 간헐적 작업을 위한 상시 서버의 **유휴 비용·배포·확장 관리 부담** 해소

#### 한줄 요약

- 주문이 들어온 순간에만 작업대가 열리고 처리가 끝나면 다시 닫히는 방식이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **콜드 스타트**: 재사용할 실행 환경이 없어 런타임과 코드를 새로 초기화하며 생기는 첫 요청 지연이다.
- **무상태 처리**: 함수 실행 사이의 로컬 메모리나 파일 상태가 유지된다고 가정하지 않는 설계이다.

</details>

- 이벤트 기반 **실행 환경 자동 할당·확장**
- 실행 간 로컬 상태를 보장하지 않는 **무상태 처리**
- 콜드 스타트와 재시도에 따른 **지연·중복 처리**

#### 한줄 요약

- 필요할 때만 실행되므로 효율적이지만 첫 실행 준비 시간과 중복 이벤트를 설계해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **트리거(Trigger)**: 하이퍼텍스트 전송 프로토콜 요청·메시지·파일 생성 등 함수 실행을 시작하는 이벤트 규칙이다.
- **외부 상태 저장소**: 실행 환경과 분리해 영속 상태·멱등 키·처리 결과를 보관하는 저장소이다.

</details>

트리거는 **하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol, HTTP) 요청**, 메시지, 파일 생성 같은 이벤트를 함수 런타임에 연결한다.

```mermaid
block-beta
  columns 3
  source["이벤트 소스"]
  trigger["트리거·라우터"]
  runtime["함수 런타임"]
  function["함수 코드"]
  state["외부 상태 저장소"]
  source --- trigger
  trigger --- runtime
  runtime --- function
  function --- state
```

| 구성요소 | 책임 |
|:---|:---|
| **이벤트 소스** | 요청·메시지·스케줄 이벤트 생성 |
| **트리거·라우터** | 이벤트 조건 평가와 대상 함수 연결 |
| **함수 런타임** | 격리 환경 준비·확장·회수 |
| **함수 코드** | 단일 책임의 업무 로직 수행 |
| **외부 상태 저장소** | 영속 상태·멱등 키·결과 저장 |

#### 한줄 요약

- 접수 창구가 주문을 알맞은 작업대에 보내고 결과와 처리 기록은 별도 장부에 남긴다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **멱등성(Idempotency)**: 같은 이벤트를 반복 처리해도 최종 상태가 한 번 처리한 것과 같게 유지되는 성질이다.
- **조건부 쓰기**: 기존 값이나 버전이 지정 조건을 만족할 때만 상태 변경을 허용하는 저장 연산이다.

</details>

**서비스형 함수(Function as a Service, FaaS)**, 서버리스 컨테이너, 상시 실행 서비스는 함수·이미지·프로세스 중 실행 관리 단위가 다르다.

```mermaid
sequenceDiagram
  participant E as 이벤트 소스
  participant T as 트리거·라우터
  participant R as 함수 런타임
  participant F as 함수 코드
  participant S as 외부 상태 저장소
  E->>T: 이벤트 전달
  T->>R: 1. 함수 호출 요청
  R->>F: 2. 실행 환경 할당
  F->>S: 3. 멱등 확인·상태 반영
  S-->>T: 처리 결과 반환
```

1. **함수 호출 요청**: 조건과 대상 함수 및 동시성 정책 확인
2. **실행 환경 할당**: 기존 환경 재사용 또는 새 환경 기동
3. **멱등 확인·상태 반영**: 중복 키 검사 후 업무 결과 저장

#### 한줄 요약

- 같은 주문이 다시 와도 주문 번호를 확인해 한 번만 반영하고 실패하면 정해진 규칙으로 재처리한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **서버리스 컨테이너**: 사용자가 제공한 컨테이너 이미지를 요청량에 따라 자동 기동·확장하는 실행 모델이다.
- **상시 실행 서비스**: 요청 유무와 관계없이 프로세스와 자원을 계속 유지하는 실행 모델이다.

</details>

| 실행 모델 | FaaS | 서버리스 컨테이너 | 상시 실행 서비스 |
|:---|:---|:---|:---|
| 적용 기준 | 짧고 독립적인 **이벤트 작업** | 컨테이너 단위 **요청·작업** | **지속 연결·장기 실행** |
| 핵심 특징 | 함수 단위 **자동 확장·종량 과금** | 이미지 단위 **배포·자동 확장** | 상시 **프로세스·자원 제어** |
| 한계 | **시간·런타임·상태 제약** | **이미지 관리·기동 비용** | **유휴 비용·운영 부담** |

#### 한줄 요약

- 짧은 일은 함수, 묶음 작업은 컨테이너, 계속 켜 둘 업무는 상시 서비스가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **꼬리 지연**: 요청 지연 분포에서 가장 느린 상위 백분위 구간의 응답 시간이다.
- **데드 레터 큐(Dead Letter Queue, DLQ)**: 반복 처리에 실패한 이벤트를 격리해 조사·재처리하도록 보관하는 큐이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **콜드 스타트**로 인한 응답 지연 | **사전 준비 인스턴스**·경량 의존성 적용 | **꼬리 지연** 감소 |
| 재시도에 따른 중복 처리 | **멱등 키·조건부 쓰기** 적용 | 이중 결제·중복 반영 방지 |
| **동시성 급증**으로 후단 과부하 | **동시성 한도·큐·데드 레터 큐(Dead Letter Queue, DLQ)** 구성 | **장애 전파·이벤트 유실** 억제 |

#### 한줄 요약

- 결제 함수는 주문 번호를 멱등 키로 저장하고 동시 실행 수를 제한해 데이터베이스를 보호한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **독립 이벤트 작업**: 다른 요청과 장기 실행 상태에 직접 의존하지 않고 하나의 입력으로 끝낼 수 있는 작업이다.
- **동시성 한도**: 함수가 한 시점에 병렬 실행할 수 있는 인스턴스 수를 제한한 값이다.

</details>

- 실행 시간이 짧고 **멱등성·외부 상태**를 확보한 독립 이벤트 작업에 **서비스형 함수(Function as a Service, FaaS)** 적용

#### 한줄 요약

- 함수 작성뿐 아니라 중복 이벤트와 순간 폭주 및 상태 저장까지 함께 설계해야 안정적으로 쓸 수 있다.
