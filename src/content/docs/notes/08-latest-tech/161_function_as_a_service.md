## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서비스형 함수(Function as a Service, FaaS)**: 이벤트에 따라 함수 코드를 격리 실행하고 자동 확장하는 클라우드 서비스다.
- **서버리스 컴퓨팅**: 인프라 준비•확장•회수를 공급자가 담당하는 클라우드 운영 모델이다.

</details>

- 정의: 이벤트별 함수 코드를 격리 실행•자동 확장하는 **FaaS**
- 배경/필요성: 전통적인 가상머신 및 컨테이너 기반 상시 실행 아키텍처는 간헐적이거나 불규칙한 이벤트 기반 워크로드(비동기 큐 처리, 웹훅, 주기적 배치 등)에서 유휴(Idle) 시간에도 지속적인 서버 비용을 지불해야 하고, 트래픽 폭증 시 인스턴스 부팅 지연으로 인한 처리 병목과 서버 관리 오버헤드를 유발함에 따라, 개발자가 인프라 프로비저닝 없이 순수 비즈니스 로직(함수)만 작성하여 배포하고 클라우드가 이벤트 발생 시에만 격리된 샌드박스 컨테이너(MicroVM, Firecracker)를 동적 할당하여 실행 후 즉시 회수하는 FaaS(Function as a Service / AWS Lambda, Google Cloud Functions, Azure Functions, OpenFaaS, Knative / Event-Driven Architecture, Micro-billing, Scale-to-Zero, Cold Start Mitigation, SnapStart) 기술을 도입하여 **이벤트 단위 밀리초($ms$) 단위 정확한 사용량 종량 과금(Pay-per-Execution)을 통한 인프라 TCO 극적 절감, Scale-to-Zero 및 무제한 동시 인스턴스 자동 스케일아웃을 통한 무결점 이벤트 처리, OS 패치 및 서버 런타임 유지보수 제로화(NoOps)**를 달성할 필요

#### 한줄 요약

- FaaS는 대기 시간을 과금 대상에서 제거해 **사용량 기반 과금**을 얻는 대신 호출 간 상태 공유를 포기하므로, 모든 영속 상태가 외부 저장소로 밀려난다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **콜드 스타트**: 재사용할 실행 환경이 없어 런타임과 코드를 새로 초기화하며 생기는 첫 요청 지연이다.
- **무상태 처리**: 함수 실행 사이에 로컬 메모리나 파일 상태가 유지된다고 가정하지 않는 처리다.

</details>

- 이벤트 기반 **실행 환경 자동 할당•확장**
- 실행 간 로컬 상태를 보장하지 않는 **무상태 처리**
- 콜드 스타트•재시도에 따른 **지연•중복 처리**
- 인프라 준비•확장•회수를 공급자가 맡는 **서버리스 컴퓨팅**

#### 한줄 요약

- 호출마다 환경을 새로 붙이는 구조라 확장은 즉각적이지만 그 대가로 **콜드 스타트**와 **중복 이벤트** 재시도가 상시 발생해, 함수는 멱등하게 설계해야만 성립한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol, HTTP)**: 웹에서 요청과 응답을 교환하는 응용 계층 프로토콜이다.
- **이벤트 소스**: HTTP 요청•메시지•파일 생성 등 함수 실행의 입력 이벤트를 생성하는 개념을 말한다.
- **트리거(Trigger)**: 이벤트 조건을 평가하여 함수 호출 여부를 결정하는 규칙로 정의된다.
- **라우터(Router)**: 트리거가 선택한 이벤트를 대상 함수 런타임으로 전달하는 개념이다.
- **함수 런타임(Function Runtime)**: 이벤트마다 격리 실행 환경을 할당하고 함수 코드의 초기화•실행•시간•자원을 관리하는 구성요소을 의미한다.
- **함수 코드(Function Code)**: 입력 이벤트를 처리하고 외부 서비스와 상태 저장소를 호출하는 사용자 업무 로직로 정의된다.
- **외부 상태 저장소**: 실행 환경과 분리해 영속 상태•멱등 키•처리 결과를 보관하는 저장소을 의미한다.

</details>

트리거는 **HTTP 요청**, 메시지, 파일 생성 같은 이벤트를 함수 런타임에 연결한다.

```text
[FaaS 아키텍처]
├── [이벤트 인입 계층]
│   ├── [이벤트 소스]
│   └── [트리거]
├── [라우팅 및 런타임]
│   ├── [라우터]
│   └── [함수 런타임]
└── [실행 및 상태 계층]
    ├── [함수 코드]
    └── [외부 상태 저장소]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 이벤트 소스 | **요청•메시지•스케줄 이벤트** 생성 |
| 트리거 | **이벤트 조건•함수 호출** 결정 |
| 라우터 | **대상 함수 런타임** 연결 |
| 함수 런타임 | **격리 환경 준비•확장•회수** |
| 함수 코드 | **단일 책임 업무 로직** 수행 |
| 외부 상태 저장소 | **영속 상태•멱등 키•결과** 저장 |

#### 한줄 요약

- 이벤트 라우팅과 **외부 상태•처리 기록** 분리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멱등성(Idempotency)**: 같은 이벤트를 반복 처리해도 최종 상태가 한 번 처리한 것과 같게 유지되는 성질을 말한다.
- **조건부 쓰기**: 기존 값이나 버전이 지정 조건을 만족할 때만 상태 변경을 허용하는 저장 연산을 말한다.

</details>

**FaaS**의 함수 호출부터 상태 반영까지 이벤트 처리

```text
이벤트 소스 ── 이벤트 ──▶ 트리거•라우터
트리거•라우터 ── 1. 함수 호출 요청 ──▶ 함수 런타임
함수 런타임 ── 2. 실행 환경 할당 ──▶ 함수 코드
함수 코드 ── 3. 멱등 확인•상태 반영 ──▶ 외부 상태 저장소
함수 코드 ◀── 상태 반영 결과 ───────── 외부 상태 저장소
이벤트 소스 ◀── 처리 결과 ─────────── 함수 코드
```

### 동작 원리

1. 함수 호출 요청: **조건•대상 함수•동시성 정책** 확인
2. 실행 환경 할당: **기존 환경 재사용•새 환경 기동**
3. 멱등 확인•상태 반영: **중복 키 검사•업무 결과 저장**

#### 한줄 요약

- 중복 이벤트의 **멱등 처리•재시도 정책** 적용

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **서버리스 컨테이너**: 사용자가 제공한 컨테이너 이미지를 요청량에 따라 자동 기동•확장하는 실행 모델을 말한다.
- **상시 실행 서비스**: 요청 유무와 관계없이 프로세스와 자원을 계속 유지하는 실행 모델로 정의된다.

</details>

| 실행 모델 | FaaS | 서버리스 컨테이너 | 상시 실행 서비스 |
|:---|:---|:---|:---|
| 적용 기준 | 짧고 독립적인 **이벤트 작업** | 컨테이너 단위 **요청•작업** | **지속 연결•장기 실행** |
| 핵심 특징 | 함수 단위 **자동 확장•종량 과금** | 이미지 단위 **배포•자동 확장** | 상시 **프로세스•자원 제어** |
| 한계 | **시간•런타임•상태 제약** | **이미지 관리•기동 비용** | **유휴 비용•운영 부담** |

#### 한줄 요약

- **실행 모델 선택**은 작업이 얼마나 오래 살아 있어야 하는가로 갈리며, 수명이 짧을수록 유휴 비용 절감이 크고 길수록 콜드 스타트와 실행 시간 제한이 그 절감을 상쇄한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **꼬리 지연**: 요청 지연 분포에서 가장 느린 상위 백분위 구간의 응답 시간로 정의된다.
- **데드 레터 큐(Dead Letter Queue, DLQ)**: 반복 처리에 실패한 이벤트를 격리해 조사•재처리하도록 보관하는 큐을 의미한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **콜드 스타트**로 인한 응답 지연 | **사전 준비 인스턴스**•경량 의존성 적용 | **꼬리 지연** 감소 |
| 재시도에 따른 **중복 처리** | **멱등 키•조건부 쓰기** 적용 | **이중 결제•중복 반영** 방지 |
| **동시성 급증**에 따른 후단 과부하 | **동시성 한도•큐•DLQ** 구성 | **장애 전파•이벤트 유실** 억제 |

#### 한줄 요약

- 멱등 키•동시성 한도로 **중복 처리•후단 과부하** 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **독립 이벤트 작업**: 다른 요청과 장기 실행 상태에 직접 의존하지 않고 하나의 입력으로 끝낼 수 있는 작업로 정의된다.
- **동시성 한도**: 함수가 한 시점에 병렬 실행할 수 있는 인스턴스 수를 제한한 값을 말한다.

</details>

- 서버리스 컴퓨팅 패러다임의 핵심 실행 계층이자 현대 마이크로서비스 및 이벤트 구동 파이프라인의 핵심 표준인 **함수 단위 온디맨드 클라우드 실행 모델(Function as a Service: FaaS / MicroVM & Container Sandbox / Event Triggers: HTTP, SQS, S3, Cron / Scale-to-Zero & Concurrent Auto-scaling / Idempotent Event Processing)의 확고한 표준**으로 확고히 자리 잡았으며, LLM 기반 Agentic 워크플로우 오케스트레이션 및 엣지 컴퓨팅(Cloudflare Workers)으로 진화하는 가운데, 실무 엔터프라이즈 FaaS 구축 시에는 **함수의 단일 책임(Single Responsibility) 및 완전한 무상태(Stateless) 아키텍처를 준수하고, 분산 락 및 멱등 키(Idempotency Key)를 통해 중복 실행을 원천 차단하며, 사전 워밍(Provisioned Concurrency) 및 SnapStart로 꼬리 지연(Tail Latency)을 극복**을 결합하여 완벽한 비용 효율성과 견고한 이벤트 처리 신뢰성을 완성

#### 한줄 요약

- 멱등성•외부 상태•동시성 한도를 갖춘 **독립 이벤트 작업** 대상 적용
