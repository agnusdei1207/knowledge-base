## 미리 알고가기

- **FaaS(파스)**: Function as a Service의 머리글자로, 이벤트에 따라 함수 단위 코드를 실행하는 서버리스 유형
- **트리거(Trigger)**: HTTP·메시지·파일 생성 등 함수 실행을 시작하는 이벤트 연결 규칙
- **멱등성(Idempotency)**: 같은 이벤트를 반복 처리해도 결과가 한 번 처리한 것과 같도록 보장하는 성질



## Ⅰ. 개요

- **정의/개념**: 이벤트 발생 시 함수 코드를 격리 환경에서 실행하고 자동 확장하는 서버리스 서비스다
- **기존 한계**: 간헐적 작업을 상시 서버로 운영하면 유휴 비용과 배포·확장 관리 부담이 발생한다
- **배경/필요성**: 짧고 독립적인 이벤트 처리를 실행량에 맞춰 운영하기 위함이다

### 쉽게 이해하기 (학습용)

- FaaS는 주문마다 필요한 작업만 시켜 끝나면 돌려보내는 방식이다.

## Ⅱ. 특징

- 이벤트마다 함수 실행 환경을 자동 할당·확장한다
- 실행 환경의 지속을 보장하지 않아 상태를 외부에 저장한다
- 콜드 스타트·실행 한도·재시도에 따른 중복 처리를 관리한다

### 쉽게 이해하기 (학습용)

- 첫 호출은 작업 공간을 준비해 느리지만 재사용하면 준비 시간이 줄어든다.

## Ⅲ. 아키텍처 및 구성요소

```text
[이벤트] → [트리거] → [실행 환경]
                         ↓
                  [함수] ↔ [외부 상태]
```

| 설계 요소 | 설명 |
|:---|:---|
| 이벤트 소스 | 함수 실행 이벤트 생성 |
| 트리거·바인딩 | 이벤트와 대상 함수 연결 |
| 실행 플랫폼 | 환경 생성·재사용·회수 |
| 함수 핸들러 | 단일 책임 로직 수행 |
| 외부 상태 | 영속 상태·멱등 키 저장 |

> 요약: 이벤트·실행 환경·외부 상태를 연결한다

### 쉽게 이해하기 (학습용)

- 실행 공간은 사라질 수 있어 중요한 기록은 외부 장부에 남겨야 한다.

## Ⅳ. 원리 및 절차 흐름도

```text
이벤트수신
    ↓
환경확인
    ↓
함수실행
    ↓
상태반영
    ↓
완료처리
```

| 절차 | 설명 |
|:---|:---|
| 이벤트 수신 | 이벤트·호출 식별자 확보 |
| 트리거 적용 | 함수·동시성·재시도 확인 |
| 환경 준비 | 환경 초기화 또는 재사용 |
| 함수 호출 | 제한 시간 안에 로직 수행 |
| 상태 반영 | 결과·멱등 키 원자적 기록 |
| 완료 처리 | 확인·재시도·실패 큐 분기 |

> 요약: 환경을 준비해 실행하고 결과를 외부에 기록한다

### 쉽게 이해하기 (학습용)

- 주문 번호를 외부에서 확인해 같은 작업이 두 번 실행되지 않게 한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | FaaS | 서버리스 컨테이너 | 상시 실행 서비스 |
|:---|:---|:---|:---|
| 적용 기준 | 짧고 독립적인 이벤트 | 사용자 이미지·긴 요청 | 지속 트래픽·장기 연결 |
| 핵심 특징 | 함수 단위 자동 확장 | 컨테이너 단위 자동 확장 | 상시 프로세스와 자원 제어 |
| 한계 | 실행 시간·환경 제약 | 콜드 스타트와 이미지 비용 | 유휴 비용과 운영 부담 |

> 요약: 실행 수명·상태·제어 범위로 모델을 고른다

### 쉽게 이해하기 (학습용)

- 짧은 일은 함수, 긴 일은 컨테이너, 지속 업무는 상시 서비스가 알맞다.

## Ⅵ. 실무 사례

1. 객체 이벤트로 썸네일 함수를 실행한다
2. 웹훅은 준비 환경과 큐로 지연을 낮춘다

### 쉽게 이해하기 (학습용)

- 이미지 키를 멱등 키로 써 중복 변환을 막고 실패는 큐로 보낸다.
- 지연 민감 웹훅은 환경을 미리 준비하고 후속 작업을 큐로 넘긴다.

## Ⅶ. 결론

- 짧은 이벤트 작업은 지연·재시도·하류 용량을 확인해 적용한다.

### 쉽게 이해하기 (학습용)

- 함수 수만 늘리지 말고 저장소와 API가 감당할 만큼만 작업을 보낸다.
