## 미리 알고가기

- **서버리스(Serverless)**: 서버가 없다는 뜻이 아니라 공급자가 서버 운영·자동 확장·용량 할당을 관리하는 클라우드 실행 모델
- **FaaS(파스)**: Function as a Service의 머리글자로, 이벤트마다 함수 코드를 실행하는 서버리스 유형
- **BaaS(바스)**: Backend as a Service의 머리글자로, 인증·DB 등 완성된 백엔드 기능을 API로 제공



## Ⅰ. 개요

- 정의/개념: 공급자가 인프라 운영과 자동 확장을 맡고 사용자가 코드·서비스 조합에 집중하는 실행 모델이다
- 기존 한계: 상시 서버는 간헐적 요청에도 용량 확보와 운영 관리가 필요해 유휴 비용이 발생한다
- **배경/필요성**: 변동 워크로드의 인프라 운영 부담과 유휴 자원 비용을 줄이기 위함이다

### 쉽게 이해하기 (학습용)

- 주문과 조리법만 보내면 공급자가 주방을 조절해 처리하고 사용분을 정산하는 방식임

## Ⅱ. 특징

- 요청량에 따라 실행 자원을 자동 할당·회수하고 사용량을 계량한다
- FaaS·BaaS·서버리스 컨테이너 등 관리형 구성 요소를 조합한다
- 콜드 스타트·실행 제한·공급자 종속을 고려해야 한다

### 쉽게 이해하기 (학습용)

- 주문 시 주방을 새로 열면 첫 처리가 지연되고 장부는 외부에 기록한다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 이벤트·요청 | 웹·메시지·일정 등으로 실행을 개시함 |
| 실행·확장 | 격리 환경 준비 및 인스턴스 자동 조정 |
| 함수·코드 | 입력 처리 및 응답·후속 이벤트 생성 |
| 서비스 백엔드 | 인증·DB 등 완성 기능 제공 |
| 외부 상태·운영 | 영속 상태 저장 및 사용량 계량 |

> 요약: 이벤트가 코드·백엔드를 잇고 운영 정보는 외부화한다.

### 쉽게 이해하기 (학습용)

- 주문 창구, 필요할 때 여는 주방, 조리 담당 코드, 빌려 쓰는 결제·장부, 별도 기록·감사 창고가 연결된 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
이벤트·요청 → 환경존재?
           ├─ 있음 → 재사용 ──┐
           └─ 없음 → 초기화 ──┤
                             ↓
                          코드실행
                             ↓
                      외부기록·계량
```

| 절차 | 설명 |
|:---|:---|
| 이벤트수신 | 요청 인증 및 함수·서비스 전달 |
| 환경선택 | 환경 재사용 또는 새 환경 초기화 |
| 코드실행 | 입력 처리 및 후속 동작 호출 |
| 상태처리 | 데이터·진행 상태를 외부 저장소 기록 |
| 응답계량 | 응답 생성 및 자원 사용량 계량 |

> 요약: 요청 때 환경·코드를 실행하고 사용량을 잰다.

### 쉽게 이해하기 (학습용)

- 준비된 환경이 없으면 초기화 지연이 생기며 결과와 상태는 외부에 기록한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 서비스형 함수 | 서비스형 백엔드 | 서버리스 컨테이너 |
|:---|:---|:---|:---|
| 적용 기준 | 짧고 독립적인 이벤트 처리 | 공통 백엔드 기능 활용 | 사용자 런타임·이미지 필요 |
| 핵심 특징 | 함수 단위 실행·자동 확장 | 완성 기능을 API로 소비 | 컨테이너 단위 자동 확장 |
| 한계 | 실행 시간·환경 제약 | 공급자 기능·정책 종속 | 함수보다 큰 시작·운영 비용 |

> 요약: 실행 단위와 제어 범위로 서버리스 유형을 선택한다

### 쉽게 이해하기 (학습용)

- 조리법 한 단계만 맡기면 함수, 완성된 결제·회원 장부를 빌리면 백엔드, 포장한 이동식 주방을 맡기면 서버리스 컨테이너임

## Ⅵ. 실무 사례

1. 이미지 업로드 이벤트로 축소 함수를 실행하고 상태를 외부에 기록한다

### 쉽게 이해하기 (학습용)

- 사진은 업로드 때만 변환하고 지연 민감 함수는 실행 환경을 미리 준비한다.

## Ⅶ. 결론

- 서버 운영 없이 변동 요청에 탄력 대응하기 위해 **호출 변동·콜드 스타트·실행시간·상태·종속성·비용**을 검토하고, 짧고 상태 외부화가 가능한 업무에 서버리스를 적용한다

### 쉽게 이해하기 (학습용)

- 요청 때만 실행하고 장기 상태는 외부에 보관한다
