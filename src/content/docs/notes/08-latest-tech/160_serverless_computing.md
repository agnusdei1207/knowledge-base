## 미리 알고가기

- **서버리스 (Serverless)**: 플랫폼 제공자가 인프라 운영, 자동 확장 및 과금을 책임지는 실행 모델



## Ⅰ. 개요

- **정의/개념**: 공급자가 실행 인프라를 운영·확장
- **배경/필요성**: 변동 요청의 유휴 비용·운영 부담 감소

### 쉽게 이해하기 (학습용)

- 주문과 조리법만 보내면 공급자가 주방을 조절해 처리하고 사용분을 정산하는 방식임

## Ⅱ. 특징

- FaaS는 이벤트별 실행 환경을 자동 확장한다
- BaaS는 공급자의 완성 기능을 조합한다
- 콜드스타트는 첫 호출 지연을 늘린다
- 영속 상태는 외부 저장소에 기록한다

### 쉽게 이해하기 (학습용)

- 주문 즉시 주방을 열면 첫 주문은 지연되고, 장부는 별도 외부 보관소에 기록함

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 이벤트·요청 | 웹·메시지·일정 등으로 실행을 개시함 |
| 실행·확장 | 격리 환경 준비 및 인스턴스 자동 조정 |
| 함수·코드 | 입력 처리 및 응답·후속 이벤트 생성 |
| 서비스 백엔드 | 인증·DB 등 완성 기능 제공 |
| 외부 상태·운영 | 영속 상태 저장 및 사용량 계량 |

> 요약: 이벤트가 코드·백엔드를 잇고 운영 정보는 외부화한다.

### 쉽게 이해하기 (학습용)

- 주문 창구, 필요할 때 여는 주방, 조리 담당 코드, 빌려 쓰는 결제·장부, 별도 기록·감사 창고가 연결된 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
이벤트·요청 → 환경존재?
           ├─ 있음 → 재사용 ──┐
           └─ 없음 → 초기화 ──┤
                             ↓
                          코드실행
                             ↓
                      외부기록·계량
```

| 절차 | 설명 |
|:---|:---|
| 이벤트수신 | 요청 인증 및 함수·서비스 전달 |
| 환경선택 | 환경 재사용 또는 새 환경 초기화 |
| 코드실행 | 입력 처리 및 후속 동작 호출 |
| 상태처리 | 데이터·진행 상태를 외부 저장소 기록 |
| 응답계량 | 응답 생성 및 자원 사용량 계량 |

> 요약: 요청 때 환경·코드를 실행하고 사용량을 잰다.

### 쉽게 이해하기 (학습용)

- 준비된 주방이 없으면 처음부터 열어 지연이 생기고, 처리가 끝나면 결과와 장부를 외부에 남긴 뒤 사용한 만큼 계산함

## Ⅴ. 종류 및 비교

| 판단 기준 | 서비스형 함수 | 서비스형 백엔드 | 서버리스 컨테이너 |
|:---|:---|:---|:---|
| 배포 | 이벤트 처리 함수 코드 | 완성 기능 API | 컨테이너 이미지 |
| 수명·상태 | 짧은 실행, 외부 상태 | 공급자가 가용성 관리 | 요청 수명, 외부 상태 |
| 적용 | 세분화된 이벤트 처리 | 공통 기능 활용 | 실행 환경 제어 필요 시 |

> 요약: 필요 기능에 따라 함수, 백엔드, 컨테이너 모델을 선택함

### 쉽게 이해하기 (학습용)

- 조리법 한 단계만 맡기면 함수, 완성된 결제·회원 장부를 빌리면 백엔드, 포장한 이동식 주방을 맡기면 서버리스 컨테이너임

## Ⅵ. 실무 사례

1. 이미지 업로드 서비스는 파일 생성 이벤트로 축소 함수를 실행하고 결과·처리 상태를 외부 저장소에 기록함
2. 지연 민감 결제 접속점은 사전 준비 실행 환경을 두고 세션·거래 상태는 관리형 데이터 저장소에 보관함

### 쉽게 이해하기 (학습용)

- 사진이 들어올 때만 변환 작업을 열고, 첫 응답이 중요한 결제는 주방을 미리 준비하되 고객 장부는 항상 외부에 보관함

## Ⅶ. 결론

- 콜드스타트·상태·비용으로 적용 모델을 고른다

### 쉽게 이해하기 (학습용)

- 요청 때만 실행하고 장기 상태는 외부에 보관한다
