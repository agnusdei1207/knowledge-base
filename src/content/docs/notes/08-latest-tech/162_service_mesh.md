## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **서비스 메시(Service Mesh)**: 애플리케이션 밖에서 서비스 간 통신 정책을 집행하는 인프라 계층이다.
- **동서 트래픽(East-West Traffic)**: 내부 서비스 사이를 오가는 호출 트래픽을 의미한다.

</details>

- 정의: 데이터 평면에서 서비스 간 정책을 집행하는 **서비스 메시**
- 배경/필요성: 대규모 마이크로서비스 아키텍처(MSA) 환경에서 수백~수천 개의 다국어(Polyglot) 서비스 간 통신(East-West Traffic)이 폭증함에 따라, 애플리케이션 코드 내부에 mTLS 암호화, 서비스 디스커버리, 재시도/서킷브레이커, 분산 추적 로직을 중복 구현하는 방식은 언어별 SDK 유지보수 비용 폭증, 보안 정책 불일치, 그리고 서비스 간 장애 연쇄 전파(Cascading Failure)의 치명적 한계에 직면함에 따라, 애플리케이션 코드를 전혀 수정하지 않고 네트워크 인프라 계층에서 서비스 간 통신을 가로채어 보안, 트래픽 제어, 가시성을 중앙에서 일괄 집행하는 전용 인프라 계층인 서비스 메시(Service Mesh / Control Plane: Istiod, Consul, Linkerd vs Data Plane: Envoy Proxy, Ambient ztunnel, Cilium eBPF, Mutual TLS: mTLS, Layer 7 Traffic Management, Circuit Breaker, Distributed Tracing)를 도입하여 **제로 트러스트(Zero Trust) 기반 자동 상호 TLS(mTLS) 암호화 및 세분화된 인가(RBAC) 정책의 전사 일괄 적용, 카나리/A-B 배포 및 L7 동적 라우팅/서킷브레이커를 통한 서비스 복원력(Resilience) 극대화, 분산 추적(OpenTelemetry, Jaeger) 및 골든 시그널 지표 수집을 통한 전방위 가시성(Observability)**을 달성할 필요

#### 한줄 요약

- 서비스 메시는 **보안•라우팅•관측 정책**을 애플리케이션 밖으로 옮겨 언어 종속을 없애는 대신 모든 요청 경로에 프록시 한 단을 끼워 넣으므로, 정책 일관성을 지연과 운영 복잡성으로 사는 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 평면(Data Plane)**: 서비스 요청을 중계하며 라우팅•보안•관측 정책을 실제 집행하는 계층을 의미한다.
- **제어 평면(Control Plane)**: 서비스 정보와 정책을 데이터 평면에 배포하는 관리 계층로 정의된다.
- **상호 전송 계층 보안(mutual Transport Layer Security, mTLS)**: 통신 양쪽의 인증서를 검증하고 전송 구간을 암호화하는 방식을 말한다.

</details>

- 제어 평면의 정책 배포와 **데이터 평면의 분산 집행**
- 서비스 간 **mTLS•인가•트래픽 제어•관측**
- 업무 로직 분리와 **지연•자원•운영 복잡성 증가**

#### 한줄 요약

- 통신 기능을 업무 로직에서 떼어낸 대가로 **프록시•정책 계층 운영**이라는 새 운영 대상이 생기므로, 서비스와 언어의 수가 적으면 분리 이득보다 운영 비용이 앞선다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **서비스 레지스트리**: 서비스 인스턴스와 접속 가능한 엔드포인트 정보를 제공하는 저장소을 말한다.
- **제어 평면 정책 배포**: 서비스•인증서•라우팅•보안 정책을 계산하여 데이터 평면에 배포하는 개념이다.
- **데이터 평면 정책 집행**: 서비스 경로에서 인증•라우팅•재시도•관측 정책을 적용하는 개념이다.
- **서비스 워크로드**: 업무 로직을 수행하며 통신 기능을 데이터 평면에 위임하는 애플리케이션 인스턴스을 의미한다.
- **관측 계층**: 지표•로그•추적을 수집하여 통신 상태와 장애 원인을 분석하는 구성요소을 말한다.
- **거버넌스**: 통신 정책의 승인•변경•감사 이력을 관리하는 운영 체계을 말한다.

</details>

```text
 [서비스 레지스트리]---[제어 평면]---[거버넌스]
                            |
                       [데이터 평면]
                        /          \
             [서비스 워크로드]---[관측 계층]
```

선의 의미: 서비스 레지스트리와 거버넌스가 제어 평면의 정책 기반을 구성하고, 데이터 평면은 서비스 워크로드의 통신과 관측 계층을 연결한다.

| 구성요소 | 책임 |
|:---|:---|
| 서비스 레지스트리 | **서비스•인스턴스•엔드포인트** 정보 제공 |
| 제어 평면 | **라우팅•보안•복원력 정책** 계산•배포 |
| 데이터 평면 | **요청 중계•정책 집행** |
| 서비스 워크로드 | **업무 로직•요청 생성•응답** 수행 |
| 관측 계층 | **지표•로그•추적** 수집•상태 분석 |
| 거버넌스 | **정책 승인•변경•감사 이력** 관리 |

#### 한줄 요약

- 정책 계산은 제어 평면에 모으고 집행만 **데이터 평면의 분산 집행**으로 흩어 둔 구조라, 제어 평면이 멈춰도 이미 배포된 정책으로 통신은 계속된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **mTLS 인증서 검증**: 양쪽 인증서의 신뢰 체인•유효 기간•서비스 신원을 확인하는 절차로 정의된다.
- **복원력 정책**: 시간 제한•재시도•회로 차단으로 일시 장애의 영향을 통제하는 통신 규칙을 의미한다.

</details>

```text
제어 평면 ── 1. 통신 정책 배포 ──▶ 데이터 평면
호출 서비스 ── 서비스 요청 ──────▶ 데이터 평면
데이터 평면 ── 2. 인증•라우팅•복원력 집행 ──▶ 대상 서비스
데이터 평면 ◀── 서비스 응답 ───────────────── 대상 서비스
호출 서비스 ◀── 처리 결과 ────────────────── 데이터 평면
데이터 평면 ── 3. 통신 결과 기록 ──▶ 관측•거버넌스
```

### 동작 원리

1. 통신 정책 배포: **라우팅•mTLS•인가•재시도 규칙** 전달
2. 인증•라우팅•복원력 집행: **신원 검증•경로•시간 제한** 적용
3. 통신 결과 기록: **지연•오류•추적 정보**를 관측 계층에 전송

#### 한줄 요약

- 데이터 평면의 **신원 검증•경로 제어•결과 관측**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능과 데이터를 호출하기 위한 명세화된 접점로 정의된다.
- **API 게이트웨이**: 외부 남북 트래픽의 인증•라우팅•요율 제한을 중앙에서 집행하는 경계이다.
- **애플리케이션 라이브러리**: 업무 프로세스 안에 포함되어 서비스 호출과 복원력 기능을 실행하는 코드이다.

</details>

서비스 메시와 **API 게이트웨이**의 동서•남북 트래픽 통제 차이

| 통신 정책 위치 | 서비스 메시 | API 게이트웨이 | 애플리케이션 라이브러리 |
|:---|:---|:---|:---|
| 적용 기준 | 내부 서비스 간 **공통 정책** | 외부 진입 **API 정책** | **소규모•단일 언어** 환경 |
| 핵심 특징 | 분산 **데이터 평면** 집행 | 중앙 경계의 **남북 트래픽** 통제 | 애플리케이션 내부 **호출 제어** |
| 한계 | **프록시 지연•운영 복잡성** | 내부 **동서 트래픽** 통제 한계 | **언어 종속•정책 불일치** |

#### 한줄 요약

- **메시•게이트웨이•라이브러리**는 같은 통신 정책을 어디에 둘지의 차이이며, 경계에 두면 외부 진입만, 프로세스 안에 두면 언어별로, 데이터 평면에 두면 언어와 무관하게 집행 범위가 정해진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **재시도 예산**: 추가 요청 폭증을 막도록 원본 요청 대비 허용할 재시도 횟수나 비율을 제한한 값이다.
- **점진 배포**: 새 정책을 일부 워크로드에 먼저 적용해 영향을 확인한 뒤 범위를 넓히는 방식이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 서비스가 달성해야 할 가용성•지연 등의 목표 수준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **재시도 중첩**에 따른 요청 폭증 | 계층별 **재시도 책임•예산** 단일화 | **재시도 폭풍** 방지 |
| **프록시 지연•자원 소비** | **SLO** 기반 샘플링•자원 한도•부하 시험 | **도입 비용** 정량화 |
| 잘못된 **전역 정책** 장애 확산 | **점진 배포•정책 검증**•즉시 롤백 | **영향 범위** 제한 |

#### 한줄 요약

- 단일 재시도 책임과 **정책 점진 배포**로 장애 확산 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **정책 일관성**: 언어와 서비스 구현이 달라도 같은 통신 규칙이 동일하게 집행되는 성질을 말한다.
- **프록시 오버헤드**: 요청 중계로 추가되는 지연•중앙처리장치•메모리•운영 비용이다.

</details>

- 클라우드 네이티브 엔터프라이즈 MSA의 내부(East-West) 네트워크 거버넌스 및 제로 트러스트 보안을 완성하는 **서비스 간 통신 제어 및 관측 인프라의 최고 핵심 표준(Service Mesh / CNCF Istio & Linkerd & Cilium / Control Plane-Data Plane Architecture / Universal mTLS & L7 Traffic Policy / Circuit Breaking & Fault Injection / Sidecar vs Ambient Mesh Evolution)의 확고한 표준**으로 확고히 자리 잡았으며, 사이드카 오버헤드를 극복하는 eBPF/앰비언트(Ambient) 사이드카리스 아키텍처로 급속히 전환되는 가운데, 실무 클러스터 서비스 메시 도입 시에는 **외부 진입(North-South)은 API Gateway로, 내부 통신(East-West)은 Service Mesh로 명확히 역할 분리하고, 재시도 폭풍(Retry Storm) 방지를 위한 계층별 서킷 브레이커 설정 및 mTLS 점진적 적용(PERMISSIVE $\rightarrow$ STRICT)**을 결합하여 완벽한 네트워크 보안과 초저지연 복원력을 완성

#### 한줄 요약

- **정책 일관성** 이익이 프록시 비용보다 클 때 서비스 메시 적용
