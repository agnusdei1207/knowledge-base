## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **데이터 오염(Data Poisoning)**: AI 학습 데이터셋에 악성 표본을 주입하여 모델 판단 기준을 왜곡하고 무결성을 훼손하는 적대적 공격(Adversarial Attack)
- **학습 파이프라인 공격(Training Pipeline Attack)**: 데이터 수집, 정제, 학습 파이프라인 개입을 통해 모델 행동을 변조하는 보안 위협
</details>

- 정의/개념: 악성 표본으로 결정 경계를 조작하는 **데이터 오염**
- 배경/필요성: 현대 딥러닝 및 LLM 파이프라인은 웹 크롤링, 크라우드소싱, 외부 서드파티 데이터셋 등 개방형 소스로부터 수억 건의 대규모 데이터를 수집하여 학습에 사용하므로, 공격자가 훈련 데이터셋에 미세하게 조작된 악성 데이터(Poison Sample)를 주입할 경우, 정상적인 형식 검사를 완벽히 통과하면서도 전체 모델의 예측 성능을 급격히 떨어뜨리거나(가용성 공격) 특정 타겟 입력에 대해서만 의도된 오분류/백도어를 유발(무결성 공격)하여 배포 후 재학습에 막대한 비용을 발생시키는 치명적 보안 위협에 직면함에 따라, 데이터 수집 출처 인증, 라벨 계보 추적, 통계적 이상치 탐지 및 강건 학습(Robust Training)을 결합한 데이터 오염 방어(Data Poisoning Defense / Clean-label Detection, Data Sanitization, Certified Defenses: Randomized Smoothing, Differential Privacy Training) 체계를 도입하여 **데이터 수집 파이프라인의 엔드투엔드 무결성 및 데이터 출처 계보(Provenance & Lineage) 검증, 특징 공간(Feature Space) 내 악성 오염 표본의 조기 식별 및 격리, 오염 데이터가 일부 유입되더라도 모델 가중치에 미치는 영향을 수학적으로 상한 제한하는 강건 머신러닝 생태계 구축**을 달성할 필요

#### 한줄 요약
- 학습 데이터 무결성을 훼손해 **성능 저하•표적 오작동** 유도

## Ⅱ. 특징

- **가용성 오염**: 학습 데이터 분포를 교란하여 모델 예측 정확도를 전반적으로 하락시키는 공격
- **표적 무결성 오염**: 특정 데이터 샘플에 대해 의도된 오판을 유도하는 표적 공격
- **백도어 오염**: 특정 트리거(Trigger) 패턴 입력 시에만 공격자 의도대로 동작하도록 백도어를 주입하는 기법

#### 한줄 요약
- 전체 성능•표적•트리거에 따른 **오염 목적** 구분

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **데이터 계보(Data Lineage)**: 표본의 출처, 변환 이력, 승인 경로를 추적하는 데이터 관리 체계
- **격리 데이터셋(Isolated Dataset)**: 신규 수집된 의심 표본을 검증 전까지 승인된 학습 데이터와 분리 저장하는 공간
</details>

```text
             [기여자 권한 관리기]
                      │
             [데이터 계보 저장소]
                      │
               [격리 데이터셋]
                      │
                [버전 저장소]
                      │
                [기준 평가기]
```

선의 의미: 권한•계보•격리•버전•평가 책임의 정적 연결

| 구성요소 | 책임 |
|:---|:---|
| 기여자 권한 관리기 | 데이터 수정 **주체•범위** 제어 |
| 데이터 계보 저장소 | 표본 **출처•변환 이력** 기록 |
| 격리 데이터셋 | 미검증 표본과 **승인 자료** 격리 |
| 버전 저장소 | 승인된 **데이터셋•모델 버전** 관리 |
| 기준 평가기 | 정상 행동과 **트리거 발동** 검증 |

#### 한줄 요약

- 기여자•계보•격리•버전•평가 기반 **데이터 무결성** 보장

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **승격 판정(Promotion Decision)**: 검증된 데이터와 모델이 운영 배포 요건을 충족하는지 결정하는 승인 과정
- **출처 검증(Provenance Validation)**: 데이터 제공자의 신뢰성 및 데이터 처리 경로의 정당성 확인
</details>

```text
       공격자/기여자
     │ 1. 악성 표본 주입
     ▼
   학습 데이터 저장소
     │ 2. 오염 배치 유입
     ▼
    학습 파이프라인
     │ 3. 경계 왜곡 학습
     ▼
    오염 모델 ◀── 4. 트리거 입력 ── 공격자
    └── 5. 오작동 유발 ──▶ 피해 대상
```

### 동작 원리

1. **악성 표본 주입**: 라벨•특징 조작 표본 삽입
2. **오염 배치 유입**: 검증 우회 표본을 학습에 포함
3. **경계 왜곡 학습**: 오염 분포가 파라미터에 전이
4. **트리거 입력**: 백도어 발동 패턴 제공
5. **오작동 유발**: 표적 오판•성능 저하 발생

#### 한줄 요약

- 악성 표본이 학습 경계를 왜곡해 **표적 오작동** 유발

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **클린 라벨 오염(Clean-label Poisoning)**: 라벨은 정상으로 유지하며 데이터 특징만 미세하게 조작하여 탐지를 우회하는 공격
- **트리거 성공률(Trigger Success Rate)**: 백도어 공격에서 특정 트리거 입력 시 공격 성공 확률
</details>

- **분류**: 공격 목적에 따라 가용성, 표적 무결성, 백도어 공격으로 분류
- **차별점**: 전체 성능 영향도 및 트리거 여부에 따른 구분

| 공격 목적 | 가용성 오염 | 표적 무결성 오염 | 백도어 오염 |
|:---|:---|:---|:---|
| 적용 기준 | **전체 예측 성능** | **표적 구간 오류** | **트리거 성공률** |
| 핵심 특징 | 전반적 **성능 저하** | 특정 집단 **오판 유도** | 특정 **트리거 발동** |
| 탐지 한계 | **서비스 품질** 붕괴 | **평균 지표**에 은닉 | 정상 성능으로 **탐지 회피** |

#### 한줄 요약

- 전체 성능 저하와 **표적•트리거 오작동** 비교

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **표본 비중 급증(Sample Weight Explosion)**: 특정 데이터셋이 학습 분포를 지배하여 모델 편향을 유도하는 문제
- **은닉 변조(Stealthy Modification)**: 외관상 정상적인 데이터로 보이나 학습 결과에 치명적 영향을 주는 변조
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 특정 기여자의 **표본 비중 급증** | 기여자별 비중•권한 제한 | 분포 지배 **차단** |
| 정상 외관의 **은닉 변조** | 격리 학습•트리거 행동 비교 | 백도어 **탐지** |

#### 한줄 요약
- 기여자 비중을 제한하고 **격리 전후 행동 변화** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **격리 전후 행동 변화(Behavioral Delta Analysis)**: 오염 가능성 데이터 포함 여부에 따른 모델 출력 차이 분석
- **검증 데이터 재학습(Verified Retraining)**: 무결성이 입증된 안전한 데이터셋으로 모델을 다시 학습시키는 복구 방안
</details>

- 대규모 AI 데이터 공급망과 오픈 웹 크롤링 환경에서 모델의 학습 무결성을 위협하는 **AI 파이프라인 보안의 제1선 방어 대상(Data Poisoning / Availability vs Targeted Integrity vs Clean-Label Poisoning / Data Provenance & Lineage / Statistical Sanitization & DP-SGD Robust Learning / Verified Retraining & Pipeline Quarantine)의 확고한 표준**으로 확고히 자리 잡았으며, LLM 사전학습 코퍼스 및 RAG 벡터 DB 오염 방어로 급속히 확장되는 가운데, 실무 데이터 엔지니어링 파이프라인 구축 시에는 **기여자/데이터 소스별 비중을 엄격히 제한하고 암호학적 해시 기반의 데이터 계보를 유지하며, 학습 전 특징 공간 클러스터링 및 잔차 분석(Spectral Signature)을 통해 오염 의심 배치를 자동 격리하고, 검증된 클린 데이터셋 기반의 섀도우 모델 비교 검증**을 결합하여 완벽한 데이터 무결성과 신뢰할 수 있는 모델 학습을 완성

#### 한줄 요약
- 출처•행동 검증 실패 시 오염 배치 배제 후 **안전 버전** 복구
