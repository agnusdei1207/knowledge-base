## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 평가(Agent Evaluation)**: 과업 결과와 실행 과정의 정확성•안전성•효율성을 함께 검증하는 평가 체계.
- **실행 경로(Trajectory)**: 에이전트가 과업을 수행하며 생성한 메시지•도구 호출•상태 전이의 전체 기록.

</details>

- 정의/개념: 결과•경로•정책•비용•부작용의 **통합 평가**
- 배경/필요성: 비결정론적(Non-deterministic) LLM 기반 에이전트의 성능을 단일 텍스트 생성 결과 채점 방식(BLEU, ROUGE 등)으로만 평가할 경우, 다단계 추론(Planning), 도구 호출(Tool Calling), 상태 전이 및 권한 준수 등 실행 경로(Trajectory) 상에서 발생하는 중간 오류와 부작용(Side Effect)을 감지하지 못하는 한계가 발생함에 따라, 최종 과업 성공률과 전체 실행 경로의 정확성·안전성·비용 효율성을 종합 검증하는 에이전트 평가(Agent Evaluation) 프레임워크를 도입하여 **경로 평가(Trajectory Evaluation) 및 상태 부작용(Side-effect) 검증 체계 확립, 반복 실행 기반의 신뢰구간(Confidence Interval) 및 실패 분포 측정, LLM-as-a-Judge 및 자동 회귀 세트(Regression Set) 기반 배포 게이트웨이 구축**을 달성할 필요

#### 한줄 요약

- **목표 달성•실행 경로•권한•부작용**을 함께 재면 우연히 맞은 답을 걸러 낼 수 있지만 평가 비용이 실행 비용을 넘기 쉬우므로, 경로 평가는 고위험 도구가 걸린 구간에 집중한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **성공률(Success Rate)**: 전체 반복 실행 중 사전에 정의한 완료 조건을 충족한 실행의 비율.
- **신뢰구간(Confidence Interval)**: 반복 측정한 성공률이 일정한 신뢰 수준에서 포함될 것으로 추정하는 범위.
- **비결정성(Nondeterminism)**: 같은 입력과 조건에서도 모델의 확률적 선택에 따라 실행 결과가 달라지는 성질로 정의된다.
- **경로 평가(Trajectory Evaluation)**: 최종 결과뿐 아니라 도구 호출•상태 전이•정책 준수 등 실행 과정의 적절성을 검증하는 평가.

</details>

- **경로 평가**: 도구 호출•상태 전이의 적절성 검증
- **성공률**: 반복 실행의 완료 조건 충족 비율
- **신뢰구간**: 비결정적 결과의 분포•안정성 측정
- **회귀 평가**: 고정 과업과 운영 지표로 품질 검증

#### 한줄 요약

- **성공률•실패 분포•신뢰구간** 기반 비결정성 평가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **회귀 세트(Regression Set)**: 변경 전후 품질과 안전성 저하를 반복 확인하도록 고정한 정상•경계•공격 과업 모음.
- **배포 게이트(Deployment Gate)**: 평가 결과가 기준선과 위험 임계치를 충족할 때만 변경 배포를 허용하는 통제 지점으로 정의된다.

</details>

```text
[에이전트 종합 평가 체계]
├── [평가 벤치마크 및 데이터셋]
│   ├── 회수/도구/계획 회귀 세트
│   └── 엣지 케이스 및 레드팀 공격셋
├── [경로 및 상태 수집 (Trace)]
│   ├── 실행 경로(Trajectory) 수집기
│   └── 중간 상태 변경 및 도구 호출 로그
└── [다면 평가 및 배포 통제]
    ├── 최종 성공률 및 신뢰구간 측정
    ├── LLM-as-a-Judge 및 룰 기반 채점
    └── 기준선(Baseline) 대조 배포 게이트
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 평가 실행기 | **회귀 세트**의 정상•경계•공격 과업 반복 실행 |
| 경로 수집기 | 메시지•도구•상태•비용의 **실행 경로** 기록 |
| 결과•경로 평가기 | 완료 조건과 정책으로 **성공•안전** 판정 |
| 배포 게이트 | **기준선 회귀**와 위험 임계치로 배포 결정 |

#### 한줄 요약

- **결과•실행 경로** 기준선 대조를 통한 성능 회귀 차단

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **기준선(Baseline)**: 변경 전 시스템의 성공률•안전성•비용을 기록하여 새 버전과 비교하는 참조 성능.
- **품질 회귀(Quality Regression)**: 변경 이후 성공률이나 안전성이 기준선보다 낮아지는 현상으로 정의된다.
- **반복 실행•경로 수집(Repeated Execution/Trajectory Collection)**: 동일 과업을 여러 번 실행해 결과•도구 호출•상태 전이•부작용을 모으는 절차이다.
- **성공•안전•비용 평가(Success/Safety/Cost Evaluation)**: 완료 조건 충족률과 정책 위반 및 자원 사용량을 함께 판정하는 절차.
- **기준선 대비 회귀 판정(Baseline Regression Decision)**: 변경 버전의 지표를 기준선과 비교해 품질 저하와 위험 임계치 초과를 결정하는 절차.

</details>

```text
평가 담당자
   │ 과업•성공 조건 제시
   ▼
실행기
   │ 1. 반복 실행•경로 수집
   │ 결과•실행 경로 전달
   ▼
평가기
   │ 2. 성공•안전•비용 평가
   │ 평가 분포 제출
   ▼
배포 게이트
   │ 3. 기준선 대비 회귀 판정
   │ 배포 허용•차단 통보
   ▼
평가 담당자
```

### 동작 원리

1. **반복 실행•경로 수집**: 과업별 결과•도구•부작용 수집
2. **성공•안전•비용 평가**: 성공률•신뢰구간•실패 유형 산출
3. **기준선 대비 회귀 판정**: 품질 회귀와 위험 임계치 판정

#### 한줄 요약

- **기준선 대비 회귀 판정** 기반 배포 허용 결정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일반 생성 평가(General Generation Evaluation)**: 외부 행동 없이 생성한 출력의 정확성•관련성•문체 같은 결과 품질을 평가하는 방식.

</details>

| 평가 유형 | 에이전트 평가 | 일반 생성 평가 |
|:---|:---|:---|
| 적용 기준 | 외부 행동•상태 변경 시스템 시 적용 | 결과만 생성하는 모델 시 적용 |
| 핵심 특징 | 결과•도구•상태의 **경로 평가** 수행 | **일반 생성 평가** 기반 출력을 판정함 |
| 한계 | 환경 재현•반복 평가 비용 발생 | 권한•부작용•경로 결함이 누락됨 |

#### 한줄 요약

- **에이전트 평가** 기반 도구•상태•부작용 경로까지 포함

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대규모 언어 모델 심판(Large Language Model as a Judge, LLM-as-a-Judge)**: 명시된 루브릭에 따라 언어 모델이 결과 품질을 채점하는 자동 평가 방식.
- **오프라인 평가(Offline Evaluation)**: 고정 데이터셋과 모의 환경에서 변경의 품질 회귀를 반복 검증하는 방식이다.
- **온라인 평가(Online Evaluation)**: 운영 환경에서 실제 품질•안전•비용•지연과 사고율을 지속 측정하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 성공 조건이 모호한 평가 오판 | 결과•부작용•금지 행동 기준을 명시함 | 과업별 성공 판정 일관성을 확보함 |
| 단일 실행에 따른 **비결정성** 은폐 | 반복•**신뢰구간**•실패 분포를 산출함 | 우연한 성공이 아닌 안정성을 검증함 |
| 모델 심판의 편향•점수 변동 | **LLM-as-a-Judge** 활용 루브릭•교정 표본•사람 검토로 교정함 | 자동 평가 신뢰도를 통제함 |
| 오프라인과 운영의 환경 차이 | **온라인 평가** 지표를 **오프라인 평가** 회귀 세트에 환류함 | 실제 실패를 반영한 지속 평가를 달성함 |

#### 한줄 요약

- 목표 달성과 별개로 **금지 행동•상태 부작용** 판정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **배포 임계치(Deployment Threshold)**: 성공률•안전성•비용 지표가 배포를 허용하기 위해 충족해야 하는 최소 또는 최대 기준이다.
- **부작용 평가(Side-effect Evaluation)**: 목표 달성 여부와 별개로 금지 행동이나 잘못된 상태 변경이 발생했는지 검증하는 평가.

</details>

- 자율 에이전트 시스템의 신뢰성과 안전성을 수치적으로 입증하고 안전한 프로덕션 배포를 보장하는 **에이전트 품질 보증 및 거버넌스 프레임워크(Agent Evaluation / Trajectory & Side-effect Validation / LLM-as-a-Judge & Benchmark / Regression Gates & CI/CD)의 핵심 평가 표준**으로 확고히 자리 잡았으며, SWE-bench, WebArena 등 도메인 특화 인터랙티브 벤치마크로 고도화되는 가운데, 실무 에이전트 평가 파이프라인 구축 시에는 **최종 목표 달성률과 함께 도구 호출 적절성 및 금지 행동 준수를 검증하는 다차원 루브릭 수립, 모델 비결정성을 극복하기 위한 다회 반복 평가 및 통계적 신뢰구간 산출, 오프라인 모의 평가와 온라인 운영 관측 지표(지연, 토큰 비용, 이상 행동)의 유기적 피드백 루프 구축**을 결합하여 완벽한 에이전트 신뢰성과 엔지니어링 품질을 완성

#### 한줄 요약

- **성공률•안전성•비용** 임계치 충족 시 배포
