## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **페이지드 어텐션(PagedAttention)**: KV 캐시를 비연속 물리 블록에 저장하고 논리 순서를 복원하는 기법이다.
- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 K•V 벡터를 저장하여 다음 토큰 생성에 재사용하는 메모리다.

</details>

- 정의: KV Cache를 비연속 블록에 할당•매핑하는 **PagedAttention**
- 배경/필요성: 전통적인 LLM 서빙 시스템에서는 각 요청의 KV Cache를 위해 사전에 최대 문맥 길이(Max Sequence Length)에 맞춘 연속된 가상/물리 메모리 공간을 고정 할당함에 따라, 실제 생성 길이가 짧을 때 발생하는 과다 예약 낭비와 메모리 동적 할당/해제로 인한 심각한 외부 단편화(External Fragmentation)로 인해 전체 GPU VRAM의 60~80%가 낭비되는 치명적 서빙 병목이 존재함에 따라, 운영체제의 가상 메모리 페이징(Paging) 메커니즘을 어텐션 연산에 도입하여 KV Cache를 고정 크기의 비연속 물리 블록(Physical Blocks)에 동적 할당하고 블록 테이블(Block Table)로 매핑하는 PagedAttention(페이지드 어텐션) 아키텍처를 도입하여 **메모리 낭비를 제로에 가깝게 억제(내부 단편화 4% 미만 달성), 동일 프롬프트 접두사 및 빔 서치(Beam Search) 경로 간의 메모리 무복사 공유(Copy-on-Write: COW) 지원, 서빙 엔진(vLLM)의 동시 배치 처리량(Batch Size) 수배 증대**를 달성할 필요

#### 한줄 요약
- **비연속 물리 블록•블록 테이블**은 간접 참조 비용을 얹는 대신 예약 낭비와 단편화를 없애 동시 처리 요청 수를 늘리므로, 지연 한 건보다 처리량을 우선하는 서빙에서 이득이 크다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **논리 블록(Logical Block)**: 토큰 순서에 따라 모델이 연속적으로 바라보는 KV 캐시 단위다.
- **물리 블록(Physical Block)**: GPU 메모리 풀에서 실제로 할당되는 고정 크기 저장 단위다.
- **쓰기 시 복사(Copy-on-Write, COW)**: 공유 블록을 수정할 때 기존 블록은 유지하고 해당 요청의 사본만 만드는 방식이다.

</details>

- **주소 매핑**: 논리 KV 순서와 비연속 물리 블록 연결
- **동적 할당•회수**: 단편화•과예약 완화
- **공유•쓰기 시 복사**: 접두사•빔 탐색 분기 최적화

#### 한줄 요약
- **접두사 공유•COW** 기반 분기 블록만 선택 복사

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 테이블(Block Table)**: 논리 블록 번호를 실제 물리 블록 주소에 대응시키는 표다.
- **GPU(Graphics Processing Unit)**: 물리 KV 블록을 저장하고 어텐션을 병렬 처리하는 장치다.
- **물리 블록 풀**: GPU의 고정 크기 캐시 블록을 동적 할당하고 종료 후 회수하는 저장 영역.
- **페이지드 커널**: 블록 테이블을 따라 비연속 KV 블록을 조회하여 어텐션을 계산하는 전용 연산 커널로 정의된다.

</details>

```text
[PagedAttention 서빙 메모리 아키텍처]
├── [논리 KV 블록 계층 (Logical Blocks)]
│   ├── 시퀀스 토큰 순서의 연속 가상 주소
│   └── 고정 크기 블록(16/32 토큰) 단위 분할
├── [블록 매핑 테이블 (Block Table)]
│   ├── 논리 블록 번호 ↔ 물리 블록 주소 매핑
│   └── 참조 카운트(Reference Count) 관리
├── [물리 블록 풀 (Physical Block Pool)]
│   ├── GPU VRAM 비연속 고정 블록 풀
│   └── 온디맨드(On-demand) 동적 할당 및 회수
└── [어텐션 실행 및 공유 (Kernel & COW)]
    ├── 비연속 블록 인출 PagedAttention 커널
    └── 쓰기 시 복사(Copy-on-Write: COW) 분기
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 논리 KV 블록 | 토큰 시퀀스 순서에 따른 논리적 연속 캐시 주소 공간 제공 |
| 블록 매핑 테이블 | 논리 블록 번호와 물리 메모리 블록 간의 주소 변환 및 참조 횟수 추적 |
| 물리 블록 풀 | GPU VRAM 내 고정 크기 물리 블록들의 동적 할당 및 반납 생명주기 관리 |
| 어텐션 실행 커널 | 블록 테이블을 참조하여 비연속 물리 블록 메모리에서 직접 어텐션 연산 |

#### 한줄 요약
- **논리•물리 블록**과 테이블•커널•COW 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **주소 매핑**: 논리적 토큰 순서와 실제 비연속 메모리 주소의 대응 관계를 기록하는 과정.
- **참조 횟수**: 공유 물리 블록을 사용하는 요청 수로, 값이 0일 때만 블록을 안전하게 회수할 수 있다.

</details>

```text
생성 요청•예상 토큰 수
        │
        ▼
블록 할당기
        │ 1. 물리 블록 할당•주소 기록
        ▼
┌────────── 생성 종료 전 반복 ──────────┐
│ 블록 테이블                           │
│   │ 2. 논리 순서별 물리 주소 전달     │
│   ▼                                   │
│ 페이지드 커널                         │
│   └ 3. KV 조회•신규 블록 연결         │
└───────────────────────────────────────┘
        │ 요청 종료 통보
        ▼
블록 할당기
        │ 4. 참조 블록 회수
        ▼
블록 테이블
```

### 동작 원리

1. 물리 블록 할당•주소 기록: 논리 번호와 **매핑 관계** 저장
2. 논리 순서별 물리 주소 전달: 커널에 **비연속 주소 목록** 제공
3. KV 조회•신규 블록 연결: 기존 캐시 조회와 **새 물리 블록** 추가
4. 참조 블록 회수: 미참조 블록을 **재사용 가능 상태**로 전환

#### 한줄 요약
- **블록 할당•주소 전달** 후 연결•회수 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **연속 키-값 할당(Contiguous Key-Value Allocation, Contiguous KV Allocation)**: 요청별 최대 길이에 맞춘 연속 공간을 미리 예약하여 주소 계산은 단순하지만 과다 예약과 단편화가 발생한다.
</details>

| 구분 | 연속 KV 할당 | PagedAttention |
|:---|:---|:---|
| 적용 기준 | **고정 길이•낮은 동시성** | **가변 길이•높은 동시성** |
| 핵심 특징 | 요청별 **연속 최대 공간 예약** | 고정 크기 **비연속 블록 매핑** |
| 한계 | **단편화•과다 예약** | **블록 조회•전용 커널** 필요 |

#### 한줄 요약
- 고정•저동시성은 **연속 할당**, 가변•고동시성은 **PagedAttention**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **내부 단편화(Internal Fragmentation)**: 마지막 블록의 미사용 공간처럼 할당 단위 내부에서 발생하는 메모리 낭비다.
- **조회 오버헤드**: 블록이 작아질수록 늘어난 주소 변환과 메모리 접근 때문에 발생하는 처리 비용.
- **쓰기 시 복사 원자성(Copy-on-Write Atomicity, COW Atomicity)**: 공유 블록의 복사와 참조 갱신이 중간 상태 없이 하나의 연산처럼 완료되어야 하는 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 큰 블록의 **내부 단편화** | **요청 길이 분포별 블록 크기 시험** | 남는 공간 **감소** |
| 작은 블록의 **주소 조회 증가** | **커널 처리량•메모리 효율 측정** | 블록 크기 **최적화** |
| 공유 블록의 **참조 오류** | 참조 횟수•**COW 원자성 검증** | 조기 회수•데이터 오염 **방지** |

#### 한줄 요약
- **블록 크기•COW 원자성** 기반 공간과 조회 비용 절충

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **블록 크기 선택**: 내부 단편화와 주소 조회 비용을 실제 요청 길이 분포와 커널 처리량으로 함께 측정해 결정한다.

</details>

- 운영체제의 가상 메모리 페이징 철학을 GPU 고성능 딥러닝 서빙에 성공적으로 이식하여 고동시성 LLM 인프라의 사실상 표준(De-facto Standard)으로 자리 잡은 **현대 LLM 서빙 프레임워크(PagedAttention / Virtual Memory Paging / Block Table & Physical Block Pool / Copy-on-Write & Prefix Sharing / vLLM Engine)의 핵심 기반 기술**로 확고히 자리 잡았으며, SGLang의 RadixAttention, TensorRT-LLM 등으로 확장 발전하는 가운데, 실무 프로덕션 LLM 클러스터 서빙 시에는 **요청 문맥 길이 분포에 맞춘 최적 물리 블록 크기(Block Size: 16 또는 32 토큰) 튜닝, 다중 세션 및 Few-shot 템플릿의 중복 연산을 제거하는 Prefix Caching 활성화, 슬라이딩 윈도우 및 청크 프리필(Chunked Prefill)과의 통합 메모리 관리**를 결합하여 완벽한 GPU 리소스 밀도와 초고속 서빙 처리량을 완성

#### 한줄 요약
- **길이 분포•동시성**과 조회 비용에 따라 할당 방식 결정
