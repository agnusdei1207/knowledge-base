## 미리 알고가기

- **페이지드 어텐션(PagedAttention, 페이지드 어텐션)**: 운영체제 페이징에 빗댄 명칭으로, KV 캐시를 고정 크기 비연속 블록으로 관리
- **운영체제(OS)**: 가상 메모리 페이징 개념 제공
- **키·값(KV) 캐시**: 이전 토큰의 어텐션 값 재사용
- **그래픽 처리장치(GPU)**: 물리 캐시 블록 저장·연산
- **블록 테이블(Block Table)**: 논리 블록과 물리 주소 연결
- **쓰기 시 복사(Copy-on-Write, COW, 카우)**: 공유 블록을 수정할 때만 사본을 생성
- **가비지 컬렉션(Garbage Collection, GC, 지씨)**: 영문 머리글자를 딴 메모리 회수 절차로, 종료된 블록을 반환
- **핵심 판단**: 어텐션 수식보다 KV 할당 방식 최적화 중시



## Ⅰ. 개요

- 정의/개념: KV 캐시를 비연속 블록으로 관리
- 기존 한계: 연속 KV 공간 예약은 가변 길이에서 단편화·과예약
- **배경/필요성**: KV 캐시 블록의 동적 할당·공유·회수

### 쉽게 이해하기 (학습용)

- 미리 큰 공간을 확보하지 않고 필요한 만큼 조각을 받아 순서표로 연결

## Ⅱ. 특징

- 논리 KV 블록을 비연속 물리 블록에 매핑한다
- 블록 단위 동적 할당·회수로 단편화와 과예약을 줄인다
- 접두어·빔의 공유 블록은 쓰기 시 복사로 분기한다

### 쉽게 이해하기 (학습용)

- 여러 요청이 공통 앞부분 공유하다 내용 변화 시 새 페이지 사용

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| Logical KV Block | 시퀀스 토큰별 캐시 단위 |
| Physical Pool | GPU 고정 크기 블록 관리 |
| Block Table | 논리-물리 주소 매핑 |
| Paged Kernel | 분산된 블록 기반 어텐션 계산 |
| Sharing·COW | 공유·분기·복사 관리 |

```text
Logical Blocks:  [0] [1] [2]
                   |   |   |
Block Table:       7   2   9
                   |   |   |
Physical Pool:   [2] ... [7] ... [9]
```

> 요약: 블록 테이블로 논리 순서와 물리 블록 연결

### 쉽게 이해하기 (학습용)

- 논리 순서는 0·1·2지만 물리 메모리의 7·2·9번을 표로 찾아 읽음

## Ⅳ. 원리 및 절차 흐름도

```text
산정
↓
할당
↓
매핑
↓
디코드
↓
회수
```

| 절차 | 설명 |
|:---|:---|
| 산정 | 논리 블록 수 계산 |
| 할당 | 물리 풀서 블록 할당 |
| 매핑 | 테이블에 물리 주소 기록 |
| 디코드 | 블록 읽고 토큰 값 추가 |
| 회수 | 공유 분기 및 종료 시 회수 |

> 요약: 논리 블록을 비연속 할당해 쓰고 종료 시 회수함

### 쉽게 이해하기 (학습용)

- 블록이 차면 새 블록을 연결하고 종료 때 반납함

## Ⅴ. 종류 및 비교

| 판단 기준 | 연속 KV 할당 | PagedAttention |
|:---|:---|:---|
| 적용 기준 | 고정 길이·낮은 동시성 | 가변 길이·높은 동시성 |
| 핵심 특징 | 요청별 연속 공간 예약 | 고정 크기 비연속 블록 |
| 한계 | 단편화·과예약 | 블록 테이블·전용 커널 필요 |

> 요약: 가변 요청은 비연속 블록으로 단편화 절감

### 쉽게 이해하기 (학습용)

- 큰 연속 자리를 미리 비우는 방식과 작은 빈자리를 순서대로 연결해 쓰는 방식의 차이임

## Ⅵ. 실무 사례

- 블록 크기는 메모리 효율/커널 성능 고려해 조정

### 쉽게 이해하기 (학습용)

- 조각을 줄여 유연하게 나누는 기술이지 메모리 한계는 존재

## Ⅶ. 결론

- KV 단편화 완화를 위해 블록 크기·선점을 검토하여 **PagedAttention** 활용

### 쉽게 이해하기 (학습용)

- 메모리 조각을 줄여 요청 간 유연한 자원 분할 수행
