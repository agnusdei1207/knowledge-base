## 미리 알고가기

- **에이전트 플래닝(Agent Planning)**: 목표를 작업·순서·조건으로 구체화
- **과업 분해(Task Decomposition)**: 복합 목표를 검증 가능한 작업으로 분할
- **의존성(Dependency)**: 작업 간 선후 관계
- **계획 후 실행(Plan-and-Execute)**: 계획 수립과 실행을 분리하는 방식
- **재계획(Re-planning)**: 오류·환경 변화에 따라 계획 수정
- **휴리스틱(Heuristic)**: 유망한 계획을 우선하는 평가 기준
- **종료 조건(Termination Condition)**: 목표·품질·비용 한계
- **추론-행동(Reasoning and Acting, ReAct)**: 관찰마다 추론 후 행동하는 방식
- **명칭 읽기·표기**: ReAct는 ‘리액트’로 읽고 Reasoning과 Acting을 합친 표기로 추론·행동의 교대 결합을 뜻함

## Ⅰ. 개요

- 정의/개념: 목표를 작업·의존성·완료 조건으로 변환하는 과정
- 기존 한계: 단일 행동 선택은 장기 과업 누락·순서 오류 발생

### 쉽게 이해하기 (학습용)

- 목적지까지 경유지를 정하고 길이 막히면 남은 경로를 다시 잡는 과정임

## Ⅱ. 특징

- **과업 분해**: 목표를 실행·검증 가능한 작업으로 나눈다
- **의존성 계획**: 선후·병렬 관계와 완료 조건을 정한다
- **재계획**: 관찰·실패·환경 변화로 남은 계획을 수정한다

### 쉽게 이해하기 (학습용)

- 계획이 너무 크면 실행이 막히고 너무 잘게 나누면 관리할 일이 늘어남

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    subgraph P[플래닝 경계]
        G[목표·제약]
        D[분해기]
        R[계획 표현]
        X[실행기]
        E[평가·재계획기]
        G -->|목표·제약| D
        D -->|작업·의존성| R
        R -->|실행 가능 작업| X
        X -->|관찰 결과| E
        E -->|수정 계획| R
    end
    X -->|도구 호출| T[도구·환경]
    T -->|관찰| X
```

| 설계 요소 | 설명 |
|:---|:---|
| 목표·제약 | 성공·기한·예산·권한 정의 |
| 분해기 | 목표를 실행·검증 작업으로 분할 |
| 계획 표현 | 순서·의존성·완료 조건 기록 |
| 실행기 | 도구 호출과 관찰 결과 저장 |
| 평가·재계획기 | 편차·실패로 계획 수정 |

### 쉽게 이해하기 (학습용)

- 계획표에는 할 일의 순서와 필요한 도구, 완료를 확인할 증거까지 적음

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant U as 사용자
    participant P as 계획기
    participant X as 실행기
    participant E as 평가기
    U->>P: 목표전달
    P->>P: 과업분해
    P->>E: 계획검증
    E-->>X: 실행계획
    X->>X: 작업실행
    X-->>E: 결과관찰
    E->>E: 완료판정
    opt 목표 미달·환경 변화
        E->>P: 재계획요청
    end
```

| 절차 | 설명 |
|:---|:---|
| 목표전달 | 목표·완료 조건·제약 전달 |
| 과업분해 | 작업·의존성·도구 정의 |
| 계획검증 | 실행 가능성·제약 충족 확인 |
| 실행계획 | 검증된 작업·순서를 전달 |
| 작업실행 | 계획에 따라 도구·환경 조작 |
| 결과관찰 | 실행 결과와 환경 변화 수집 |
| 완료판정 | 목표·품질·비용 조건 평가 |
| 재계획요청 | 편차 발생 시 후속 계획 수정 |

### 쉽게 이해하기 (학습용)

- 실행 전 계획을 살피고 실행 후 실제 결과가 다르면 남은 부분만 다시 짬

## Ⅴ. 에이전트 계획 방식 비교

| 비교 기준 | Plan-and-Execute | ReAct |
|:---|:---|:---|
| 적용 기준 | 장기·복합·병렬 과업 | 짧고 변화가 잦은 과업 |
| 핵심 특징 | 전체 계획 후 단계 실행 | 추론·행동·관찰 반복 |
| 한계 | 계획 비용·환경 변화 취약 | 근시안적 반복·목표 이탈 |

> 요약: 과업 길이·변화 빈도로 계획 방식 선택

### 쉽게 이해하기 (학습용)

- 긴 여행은 전체 경로를 세우고 짧고 변수가 많은 길은 한 걸음씩 찾는 편이 맞음

## Ⅵ. 실무 사례

1. 데이터 분석: **의존성 계획**으로 순서·병렬성 결정
2. 코드 수정: **부분 재계획**으로 영향 작업만 갱신

### 쉽게 이해하기 (학습용)

- 데이터 분석은 원자료를 모으기 전에 분석부터 시작할 수 없으므로 작업 순서를 먼저 잡음
- 코드 수정이 실패하면 이미 끝난 일까지 반복하지 않고 영향을 받은 뒤 작업만 다시 정함

## Ⅶ. 결론

- 장기 과업은 **선행 계획**, 변화가 크면 ReAct 결합

### 쉽게 이해하기 (학습용)

- 오래 걸리고 순서가 중요한 일일수록 계획을 세우되 실제 결과에 맞춰 필요한 부분만 고쳐야 함
