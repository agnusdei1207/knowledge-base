## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 플래닝(Agent Planning)**: 목표를 실행 가능한 작업과 의존성•완료 조건으로 분해하고 수행 결과에 따라 계획을 수정하는 과정이다.
- **과업 분해(Task Decomposition)**: 복합 목표를 독립적으로 실행하고 검증할 수 있는 하위 작업으로 나누는 과정.

</details>

- 정의: 목표를 작업•의존성•완료 조건으로 변환하고 수정하는 **플래닝**
- 배경/필요성: 에이전트가 매 순간 눈앞의 다음 행동만을 즉흥적으로 결정하는 근시안적(Myopic) ReAct 방식에만 의존할 경우, 장기적 선후 관계 누락, 무의미한 반복 탐색, 전역 목표 이탈(Goal Deviation) 및 복합 작업의 의존성 충돌로 인해 전체 프로세스가 실패하는 구조적 한계가 발생함에 따라, 실행에 앞서 최상위 목표를 검증 가능한 하위 과업(Sub-tasks)과 방향성 의존성 그래프(DAG)로 체계적으로 분해하고 실행 중 동적으로 계획을 수정하는 에이전트 플래닝(Agent Planning) 기법을 도입하여 **복잡한 장기 과업의 구조적 분해 및 선후 의존성 보장, 중간 실패 및 환경 변화에 대응하는 부분 재계획(Partial Re-planning) 역량 확보, 실행 비용 및 탐색 지연의 최적화**를 달성할 필요

#### 한줄 요약

- **과업 분해•의존성 분석**은 실행 전에 오류를 걸러 내는 대신 계획 자체의 토큰·지연 비용을 선지불하므로, 환경이 자주 바뀌면 긴 계획보다 짧은 계획과 잦은 재계획이 유리하다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **의존성(Dependency)**: 어떤 작업의 시작이나 완료가 다른 작업의 결과에 좌우되는 선후 관계.
- **재계획(Re-planning)**: 오류나 환경 변화가 발생했을 때 완료 결과는 보존하고 남은 계획을 수정하는 과정으로 정의된다.
- **작업 입도(Task Granularity)**: 계획을 구성하는 하위 작업 하나의 크기로, 실행 가능성과 관리 비용 사이의 균형을 좌우하는 기준.

</details>

- **과업 분해**: 목표를 실행•검증 가능한 작업으로 분할
- **의존성**: 선후•병렬 관계와 완료 조건 정의
- **재계획**: 관찰•실패•환경 변화로 남은 계획 수정

#### 한줄 요약

- **작업 입도** 크면 실행 곤란, 작으면 관리 비용 증가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **계획 표현(Plan Representation)**: 작업 순서•의존성•완료 조건을 실행기가 해석할 수 있는 형태로 기록한 구조.
- **휴리스틱(Heuristic)**: 비용•성공 가능성 같은 기준으로 유망한 계획 후보를 우선 탐색하게 하는 평가 기준.

</details>

```text
[에이전트 플래닝(Planning) 체계]
├── [목표 및 제약 정의]
│   ├── 상위 목표(Goal) 설정
│   └── 기한·예산·권한 등 제약 조건
├── [과업 분해 및 의존성 분석]
│   ├── 과업 분해기 (Task Decomposer)
│   ├── 선후/병렬 의존성 그래프(DAG)
│   └── 계획 표현(Plan Representation)
└── [실행 및 적응형 재계획 (Feedback)]
    ├── 작업 디스패처 (실행기)
    ├── 실행 결과 관찰 및 평가기
    └── 부분 재계획기(Partial Re-planning)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 목표•제약 | 성공•기한•예산•권한 경계 정의 |
| 과업 분해기 | 목표를 실행•검증 가능한 하위 작업으로 분할 |
| 계획 표현 | 순서•의존성•완료 조건을 **계획 표현**으로 기록 |
| 실행기 | 도구 호출과 관찰 결과 저장 |
| 평가•재계획기 | **휴리스틱** 기반 후보 평가와 후속 계획 수정 |

#### 한줄 요약

- 순서•도구•완료 증거를 **계획 표현** 기반 기록

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **종료 조건(Termination Condition)**: 목표 달성도•품질•비용•반복 횟수로 계획 실행을 끝낼 시점을 정한 기준이다.
- **부분 재계획(Partial Re-planning)**: 완료된 작업은 유지하고 변화의 영향을 받은 후속 경로만 다시 수립하는 방식.
- **작업•의존성 계획 검증(Plan Validation)**: 작업의 선후 관계와 실행 가능성 및 완료 조건을 확인하는 절차로 정의된다.
- **실행 가능 작업 전달(Executable Task Delivery)**: 충족된 의존성을 기준으로 다음 실행 작업을 선택해 실행기에 넘기는 절차이다.
- **작업 결과•환경 관찰(Result and Environment Observation)**: 실제 결과와 환경 변화를 수집해 계획과의 편차를 평가하는 절차.
- **남은 계획 재수립(Remaining Plan Restablishment)**: 완료 결과는 보존하고 영향을 받은 후속 경로만 다시 계획하는 절차.

</details>

```text
사용자
   │ 목표•완료 조건 전달
   ▼
계획기
   │ 1. 작업•의존성 계획 검증
   ▼
평가기
   │ 2. 실행 가능 작업 전달
   ▼
실행기
   │ 작업 결과•환경 정보 반환
   ▼
평가기
   │ 3. 작업 결과•환경 관찰
   ├──────────────────────┐
   │ 목표 미달•환경 변화 │
   └──────────┬───────────┘
   │ 4. 남은 계획 재수립
   │ 수정된 실행 단계 반복
   │ 최종 결과•근거 반환
   ▼
사용자
```

### 동작 원리

1. 작업•의존성 계획 검증: 선후관계와 실행 가능성 확인
2. 실행 가능 작업 전달: 충족된 의존성으로 다음 작업 선택
3. 작업 결과•환경 관찰: 실제 결과와 계획 편차 평가
4. 남은 계획 재수립: 완료 결과 보존과 후속 경로 수정

#### 한줄 요약

- **계획 검증•환경 관찰** 후 영향 경로만 부분 재계획

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **계획 후 실행(Plan-and-Execute)**: 전체 계획을 먼저 수립한 뒤 각 단계를 실행하는 방식.
- **추론-행동(Reasoning and Acting, ReAct)**: 매 관찰마다 추론과 행동을 반복하여 다음 단계를 정하는 방식.

</details>

- **계획 후 실행•ReAct**를 장기 계획과 즉시 적응으로 구분

| 계획 방식 | Plan-and-Execute | ReAct |
|:---|:---|:---|
| 적용 기준 | 장기•복합•병렬 과업 처리 | 짧고 변화가 잦은 과업 처리 |
| 핵심 특징 | 전체 계획 수립 후 단계 실행 | 추론•행동•관찰의 반복 |
| 한계 | 계획 비용•환경 변화 취약 | 근시안적 반복•목표 이탈 |

> 요약: 장기 계획은 **Plan-and-Execute**, 즉시 적응은 **ReAct** 적용

#### 한줄 요약

- 장기 의존 과업은 **Plan-and-Execute**, 변동 과업은 ReAct

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **의존성 그래프(Dependency Graph)**: 작업의 선후•병렬 관계를 연결하여 실행 가능한 순서를 판정하는 구조.
- **목표 이탈(Goal Deviation)**: 반복 실행이나 재계획 중 처음의 성공 조건과 다른 방향으로 계획이 변하는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 분해에 따른 계획 비용 | **작업 입도**를 독립 검증 산출물로 제한 | 실행과 관리의 균형 확보 |
| 선행 결과 누락에 따른 순서 오류 | **의존성 그래프**의 입력•완료 조건 검증 | 실행 가능한 작업 순서 보장 |
| 환경 변화에 따른 계획 무효화 | 완료 작업 보존 후 **부분 재계획** 수립 | 재작업 없는 부분 복구 |
| 반복 재계획의 **목표 이탈** | 예산•반복 수•**종료 조건** 강제 | 무한 탐색과 비용 폭증 차단 |

#### 한줄 요약

- **의존성 그래프** 기반 실행 가능한 작업 순서 보장

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **계획 방식 결정(Planning Method Decision)**: 과업 의존성과 변화 빈도에 따라 Plan-and-Execute와 ReAct 중 선택하는 결정.

</details>

- 즉흥적 반응을 넘어 전역 목표를 향한 체계적 사고와 구조적 실행을 가능하게 하는 **에이전트 인지 아키텍처의 핵심 두뇌(Agent Planning / Task Decomposition & DAG Dependency / Plan-and-Execute vs ReAct / Partial Re-planning & Termination Condition)의 필수 설계 기법**으로 확고히 자리 잡았으며, Tree of Thoughts(ToT), LATS(Language Agent Tree Search) 등 고급 탐색 알고리즘과 결합되어 진화하는 가운데, 실무 에이전트 플래닝 구현 시에는 **과업 특성에 맞춘 계획 후 실행(Plan-and-Execute: 장기 복합 과업)과 즉각 적응형(ReAct: 동적 단기 과업)의 하이브리드 조합, 작업 입도(Granularity)의 최적화와 의존성 그래프 기반 순서 검증, 환경 변화 및 도구 오류 발생 시 완료 작업은 보존하고 후속 경로만 갱신하는 부분 재계획(Partial Re-planning) 알고리즘**을 결합하여 완벽한 목표 달성률과 연산 효율성을 완성

#### 한줄 요약

- **과업 의존성•변화 빈도**에 따라 계획 방식 결정
