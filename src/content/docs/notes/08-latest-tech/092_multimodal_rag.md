## 미리 알고가기

- **멀티모달 RAG**: 텍스트, 이미지, 표, 도면을 검색 근거로 활용하는 RAG
- **중요 요소**: 문서 파싱 품질과 모달별 검색 전략이 답변 품질을 결정
- **핵심 기술**: VLM(Vision Language Model)과 인용(Citation) 체계의 결합



## Ⅰ. 개요
- 정의/개념: 텍스트·이미지·표를 검색 근거로 쓰는 RAG
- **배경/필요성**: 텍스트 변환이 잃는 시각 관계와 위치 보존
### 쉽게 이해하기 (학습용)
- 글·그림·표의 원본 위치를 함께 찾아 답변 근거로 활용합니다.

## Ⅱ. 특징
- 텍스트·이미지·표를 표현과 메타데이터로 색인한다.
- 질의와 후보 모달을 공동 공간에서 비교·융합한다.
- 요약본을 검색한 뒤 원본 시각 자료를 다시 호출한다.
- 답변 주장을 원본 문단·표·영역과 연결해 검증한다.
### 쉽게 이해하기 (학습용)
- 글·그림 색인을 따로 만들고 질문에 맞는 후보를 모은 뒤 실제 원본과 대조합니다.

## Ⅲ. 구성요소 및 구조
| 설계 요소 | 설명 |
|:---|:---|
| 모달 추출기 | 문서에서 텍스트·이미지·표와 원본 좌표를 분리함 |
| 모달 정렬기 | 캡션·표 구조·식별자로 서로 관련된 표현을 연결함 |
| 모달 색인 | 모달별 임베딩과 문서·페이지·영역 메타데이터를 저장함 |
| 검색·융합기 | 모달별 후보 순위를 융합하고 생성 문맥을 구성함 |
| 근거 연결부 | 답변 주장과 원본 문단·표 셀·이미지 영역을 연결함 |

```text
[텍스트 색인] ──┐
[이미지 색인] ──┼→ [검색·융합기]
[표 구조 색인] ──┘         │
                            ↓
                     [생성 문맥]
                            │
                     [원본 좌표 연결]
```

### 쉽게 이해하기 (학습용)
- 추출기·정렬기·모달 색인·검색 융합기·근거 연결부가 역할을 나눕니다.

## Ⅳ. 원리 및 절차 흐름도
```text
[질의 입력]
      ↓
[모달 후보 검색]
      ↓
원본 시각자료?
  ├ 아니요 → [텍스트 문맥]
  └ 예 → [원본 영역]
      ↓
[답변 생성·근거 연결]
```
| 절차 | 설명 |
|:---|:---|
| 모달 분해 | 문서 요소와 원본 좌표를 추출함 |
| 색인 생성 | 모달별 표현과 연결 메타데이터 저장함 |
| 모달 검색 | 필요 모달 후보를 검색·정렬함 |
| 원본 호출 | 세부 시각 정보 시 원본 영역 호출함 |
| 답변 검증 | 융합 문맥 기반 답안 생성 및 근거 확인 |
### 쉽게 이해하기 (학습용)
- 질문이 시각 세부를 요구하면 요약에 그치지 않고 원본 영역을 다시 불러 답과 대조합니다.
## Ⅴ. 종류 및 비교
| 판단 기준 | 텍스트 변환 | 공동 임베딩 | 다중 표현 |
|:---|:---|:---|:---|
| 검색 표현 | 설명문으로 바꿔 색인 | 같은 벡터 공간 검색 | 모달별 표현 색인 |
| 근거 보존 | 시각 세부 손실 우려 | 이미지 단위 연결 | 문단·표·영역별 유지 |
| 적용 기준 | 시각 정보 최소 시 | 의미 검색 중심 시 | 세부 인용 필요 시 |

> 요약: 모달별 근거 연결을 통한 정확도 향상
### 쉽게 이해하기 (학습용)
- 시각 자료를 글로 바꾸는 방식, 공동 공간에서 찾는 방식, 여러 표현과 원본을 함께 쓰는 방식의 차이입니다.

## Ⅵ. 실무 사례
- 설비 검색은 절차 문장과 도면 부품 영역을 연결한다.
### 쉽게 이해하기 (학습용)
- 도면 부품이나 표의 수치를 답할 때 실제 페이지와 영역을 함께 제시할 수 있습니다.
## Ⅶ. 결론
- 문서의 텍스트·표·이미지를 함께 검색해 정확한 답변을 생성하기 위해 **양식별 파싱·원본 좌표·교차 양식 정렬·주장별 인용**을 검토하고, 근거 위치를 재현할 수 있는 멀티모달 RAG를 활용해야 한다.
### 쉽게 이해하기 (학습용)
- 글만으로 부족한 질문은 그림과 표를 검색하되 답이 원본 어디에서 나왔는지 확인해야 합니다.
