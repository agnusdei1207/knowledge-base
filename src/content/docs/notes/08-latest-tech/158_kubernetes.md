## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **쿠버네티스(Kubernetes, K8s)**: 다중 노드 환경에서 컨테이너화된 애플리케이션의 배포, 확장 및 운영을 자동화하는 오픈소스 오케스트레이션 플랫폼.
- **조정(Reconciliation)**: 쿠버네티스의 핵심 제어 루프로, 선언된 목표 상태(Desired State)와 현재 상태(Actual State)의 차이를 감시하고 동기화하여 목표 상태를 유지하는 과정.

</details>

- 정의: 컨테이너를 목표 상태로 조정•배치•복구하는 **K8s**이다.
- 배경/필요성: 다중 노드 수동 운영으로 **배치•연결•복구 상태** 불일치가 발생함.

#### 한줄 요약

- 선언한 상태와 실제 상태의 차이를 **제어 루프** 기반 축소

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **파드(Pod)**: 쿠버네티스에서 생성 및 배포 가능한 가장 작은 컴퓨팅 단위로, 하나 이상의 컨테이너가 네트워크와 저장소를 공유하며 그룹으로 실행되는 객체.
- **큐블릿(kubelet)**: 각 클러스터 노드에서 실행되며, API 서버로부터 받은 파드 명세에 따라 컨테이너를 실행하고 상태를 지속적으로 모니터링하여 제어면에 보고하는 노드 에이전트.

</details>

- Pod를 최소 배포 단위로 **선언**•**관리**
- 컨트롤러가 **목표•실제 상태 차이** 축소
- 스케줄러•kubelet의 **배치•실행 분담**

#### 한줄 요약

- 스케줄러가 배치하고 kubelet이 실행하며 **Service** 연결

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **API 서버(API Server)**: 쿠버네티스 제어면(Control Plane)의 프론트엔드 역할을 수행하며, 모든 객체 요청을 인증, 검증하고 상태 정보를 관리하는 클러스터의 중심 통신 창구.
- **etcd**: 쿠버네티스 클러스터의 모든 설정 정보, 상태 데이터, 객체 정보를 안정적으로 저장하는 고가용성 분산 키-값 저장소.
- **컨트롤러 관리자(Controller Manager)**: 클러스터의 상태를 지속적으로 감시하며, 제어 루프를 통해 목표 상태를 달성하도록 파드 생성, 복제 제어 등을 수행하는 구성 요소.
- **스케줄러(Scheduler)**: 리소스 요구사항, 제약 조건, 노드 상태 등을 고려하여 파드를 최적의 노드에 배치(Binding)하는 제어면 구성 요소.

</details>

```text
                         [API 서버]
                    /        |        \
              [etcd] [컨트롤러 관리자] [스케줄러]
                                              |
                                          [kubelet]
```

선의 의미: API 서버가 etcd, 컨트롤러 관리자, 스케줄러의 공통 제어면 창구이고, 스케줄러가 정한 노드 배치를 kubelet이 실제 컨테이너 실행으로 구현하는 관계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| API 서버 | **객체 인증•검증•제어면 통신** 창구 |
| etcd | **클러스터 구성•상태** 분산 저장 |
| 컨트롤러 관리자 | **Pod 생성•교체 요청** 조정 |
| 스케줄러 | **미배치 Pod 실행 노드** 지정 |
| kubelet | **컨테이너 실행•상태 보고** 수행 |

#### 한줄 요약

- API 서버•etcd•컨트롤러•스케줄러•**kubelet 구조**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **노드 바인딩**: 스케줄러가 미배치 Pod를 실행할 특정 노드에 연결하는 결정을 말한다.
- **준비 상태**: Pod가 서비스 요청을 정상 처리할 수 있는지 나타내는 조건이다.

</details>

API 서버는 Pod의 목표•실제 상태를 각 제어 구성요소에 전달한다.

```text
운영자 ── 선언 객체 요청 ──▶ API 서버
┌──────── 목표 상태와 실제 상태 불일치 시 ────────┐
│ API 서버 ── 1. 목표•실제 상태 감시 ──▶ 컨트롤러 관리자
│ API 서버 ◀─ 2. 부족 Pod 생성 요청 ── 컨트롤러 관리자
│ API 서버 ── 3. 미배치 Pod 감시 ──▶ 스케줄러
│ API 서버 ◀─ 4. 노드 바인딩 기록 ── 스케줄러
│ API 서버 ── 5. 바인딩된 Pod 전달 ──▶ kubelet
│ API 서버 ◀── 실행•준비 상태 ───────── kubelet
└───────────────────────────────────────────────┘
운영자 ◀── 현재 워크로드 상태 ── API 서버
```

### 동작 원리

1. 목표•실제 상태 감시: 컨트롤러의 복제본 차이를 계산함.
2. 부족 Pod 생성 요청: 필요한 미배치 Pod 객체를 생성함.
3. 미배치 Pod 감시: 스케줄 대상 Pod를 탐색함.
4. 노드 바인딩 기록: 자원•제약 기반 실행 노드를 결정함.
5. 바인딩된 Pod 전달: kubelet이 컨테이너를 실행함.

#### 한줄 요약

- 부족 Pod를 생성•배치하고 **실행•준비 상태** 활용 반복 조정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Deployment**: 교체 가능한 무상태 Pod의 복제 수와 순차 배포를 관리하는 제어기이다.
- **StatefulSet**: Pod의 고정 식별자•순서•영속 볼륨 연결을 유지하는 제어기을 의미한다.
- **DaemonSet**: 모든 대상 노드에 지정 Pod 복제본이 하나씩 실행되도록 관리하는 제어기을 의미한다.

</details>

| 워크로드 제어기 | Deployment | StatefulSet | DaemonSet |
|:---|:---|:---|:---|
| 적용 기준 | **교체 가능한 무상태 서비스** | **고정 식별•저장 작업** | **모든 대상 노드 기능 배치** |
| 핵심 특징 | **복제 수•순차 배포** 관리 | **순서•식별자•볼륨** 유지 | **노드별 Pod 복제본** 유지 |
| 한계 | **영속 상태 자체 보장 불가** | **배포•복구 순서로 확장 지연** | **노드 증가만큼 자원 증가** |

> 요약: 무상태는 **Deployment**, 상태 보존은 **StatefulSet**, 노드 상주는 **DaemonSet** 핵심이다.

#### 한줄 요약

- 무상태•고정 상태•노드 상주에 따른 **제어기 선택**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **준비 상태 검사(Readiness Probe)**: 컨테이너가 요청을 받을 준비가 되었는지 주기적으로 확인하는 검사을 의미한다.
- **자원 요청•제한**: 스케줄링에 보장할 자원량과 컨테이너가 사용할 수 있는 최대 자원량을 정한 값을 말한다.
- **서비스(Service)**: 준비된 Pod 집합에 안정적인 접근 주소와 트래픽 분산을 제공하는 객체을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 준비되지 않은 Pod로 **트래픽 오류** | 준비 상태 검사•서비스 엔드포인트 연계 | 정상 Pod만 **요청 수신** |
| 자원 요청 오류로 **스케줄 불가•축출** | 요청•제한•우선순위 기준 검증 | 노드 배치 **안정성 향상** |

#### 한줄 요약

- 준비 상태•자원 요청을 검증해 **트래픽•노드 배치** 안정화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **무상태 서비스**: 개별 Pod가 영속 상태를 소유하지 않아 다른 복제본으로 교체할 수 있는 서비스이다.
- **영속 볼륨**: Pod 수명과 분리해 데이터를 계속 보관하도록 제공하는 저장 자원을 말 체계 적용

</details>

- 무상태는 **Deployment**, 고정 식별•볼륨은 **StatefulSet** 선택

#### 한줄 요약

- 노드 상주 기능은 **DaemonSet**, 교체 가능 서비스는 Deployment
