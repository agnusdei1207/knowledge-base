## 미리 알고가기

- **쿠버네티스(Kubernetes, K8s, 케이 에이츠)**: K와 s 사이 8글자를 숫자 8로 줄여 쓰며, 컨테이너를 선언적으로 관리하는 플랫폼
- **Pod(파드)**: 하나 이상의 컨테이너가 네트워크·저장 공간을 공유하는 Kubernetes의 최소 배포 단위
- **조정(Reconciliation)**: 선언한 목표 상태와 실제 상태의 차이를 반복해서 줄이는 제어 루프



## Ⅰ. 개요

- 정의/개념: 선언한 상태에 맞춰 컨테이너 배치·확장·복구를 자동화하는 오케스트레이션 플랫폼이다
- 기존 한계: 다중 노드의 컨테이너를 수작업으로 배치하면 확장·복구·연결 상태를 일관되게 유지하기 어렵다
- 기존 한계: 다수 서버의 컨테이너를 수동 관리하면 배치·연결·확장·장애 복구 상태를 일관되게 유지하기 어렵다.

### 쉽게 이해하기 (학습용)

- 운영자가 실행 수와 버전을 선언하면 플랫폼이 실제 상태를 반복 확인해 유지한다.

## Ⅱ. 특징

- Pod를 최소 배포 단위로 선언 객체를 관리한다
- 컨트롤러가 목표 상태와 실제 상태의 차이를 조정한다
- 스케줄러·kubelet이 Pod의 노드 배치와 실행을 담당한다

### 쉽게 이해하기 (학습용)

- 배치 관리자는 장소를 정하고 현장 감독자가 실행하며, 안내 데스크는 준비된 일꾼에게 트래픽을 보냄

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| API 서버 | 객체 요청의 인증·검증과 제어면 통신 창구 |
| etcd | 클러스터 구성과 상태를 저장하는 분산 저장소 |
| 컨트롤러 관리자 | 객체를 관찰해 Pod 생성·교체 요청 |
| 스케줄러 | 미배치 Pod에 적합한 노드를 지정 |
| kubelet | 지정 노드에서 컨테이너 실행·상태 보고 |
| Service | Pod 집합의 주소 추상화 및 트래픽 전달 |

> 요약: API 서버·컨트롤러·스케줄러가 Pod를 관리한다.

### 쉽게 이해하기 (학습용)

- 주문 창구·기준 장부·감독자·자리 배정자·현장 관리자가 함께 목표 상태를 유지한다.

## Ⅳ. 원리 및 절차 흐름도

```text
선언상태 → 상태비교
             ↓
        Pod 생성필요?
      ├─ 아니요 → 대기
      └─ 예 → 노드선택
             ↓
        Pod 실행
             ↓
      준비 → 서비스갱신
```

| 절차 | 설명 |
|:---|:---|
| 상태선언 | 작업 유형·복제 수·정책을 API에 등록함 |
| 차이조정 | 컨트롤러가 선언 상태와 실제 상태 차이 계산 |
| 노드선택 | 스케줄러가 제약 조건에 맞는 노드를 결정함 |
| Pod실행 | 노드 에이전트가 컨테이너 실행 및 보고 |
| 연결복구 | 준비 상태 반영 및 실패 Pod 교체 |

> 요약: 선언 상태로 Pod를 실행해 서비스에 반영한다.

### 쉽게 이해하기 (학습용)

- 필요한 인원과 조건을 장부에 적고 부족하면 새 일꾼의 자리를 정해 투입하며, 준비된 사람만 안내하고 실패하면 교체하는 순서임

## Ⅴ. 종류 및 비교

| 판단 기준 | Deployment | StatefulSet | DaemonSet |
|:---|:---|:---|:---|
| 적용 기준 | 교체 가능한 무상태 서비스 | 고정 식별·저장이 필요한 작업 | 모든 대상 노드에 기능 배치 |
| 핵심 특징 | 복제 수와 순차 배포 관리 | 순서·식별자·볼륨 연결 유지 | 노드별 Pod 복제본 유지 |
| 한계 | 영속 상태를 자체 보장하지 않음 | 배포·복구 순서로 확장 지연 | 노드 증가만큼 자원 사용 증가 |

> 요약: 배포·상태·노드 상주 특성별 제어기를 쓴다.

### 쉽게 이해하기 (학습용)

- 아무 직원이나 대신할 수 있으면 Deployment, 이름과 개인 사물함이 필요하면 StatefulSet, 모든 지점에 한 명씩 필요하면 DaemonSet임

## Ⅵ. 실무 사례

1. 웹 서비스는 Deployment Pod를 분산하고 준비된 Pod만 Service에 연결한다

### 쉽게 이해하기 (학습용)

- 웹 서버는 복제본으로 교체할 수 있지만 손상된 데이터는 백업에서 복구해야 한다.

## Ⅶ. 결론

- 다중 노드 컨테이너의 배치·복구·확장을 자동화하기 위해 **원하는 상태·워크로드 유형·준비 상태·영속성·장애 복구**를 검토하고, 쿠버네티스의 선언형 제어를 적용한다

### 쉽게 이해하기 (학습용)

- 원하는 개수와 상태를 적으면 제어기가 계속 맞춰 준다
