## 미리 알고가기

- **쿠버네티스 (Kubernetes, K8s)**: 컨테이너의 배포, 확장 및 상태 복구를 자동화하는 선언형 오케스트레이션 플랫폼



## Ⅰ. 개요

- **정의/개념**: 선언 상태를 유지하는 오케스트레이션
- **배경/필요성**: 다중 노드 배치·복구·연결 자동화

### 쉽게 이해하기 (학습용)

- 운영자가 실행 수와 버전을 선언하면 플랫폼이 상태를 확인하여 계속 유지함

## Ⅱ. 특징

- Pod가 공유 네트워크의 최소 배포 단위다
- 스케줄러가 미배치 Pod의 노드를 고른다
- 컨트롤러가 선언·실제 상태 차이를 줄인다
- Service가 변동 Pod 주소를 추상화한다

### 쉽게 이해하기 (학습용)

- 배치 관리자는 장소를 정하고 현장 감독자가 실행하며, 안내 데스크는 준비된 일꾼에게 트래픽을 보냄

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| API 서버 | 선언 객체 검증 및 클러스터 기준 상태 저장 |
| 컨트롤러 | 작업 객체를 관찰하여 Pod 생성·교체 요청 |
| 스케줄러 | 자원·정책에 맞는 노드에 Pod 연결 |
| 노드 에이전트 | 지정 노드에서 컨테이너 실행 및 상태 보고 |
| Service | Pod 집합의 주소 추상화 및 트래픽 전달 |

> 요약: API 서버·컨트롤러·스케줄러가 Pod를 관리한다.

### 쉽게 이해하기 (학습용)

- 주문 창구와 기준 장부, 인원 감독자, 자리 배정자, 현장 관리자, 안내 데스크가 이어져 서비스 상태를 유지함

## Ⅳ. 원리 및 절차 흐름도

```text
선언상태 → 상태비교
             ↓
        Pod 생성필요?
      ├─ 아니요 → 대기
      └─ 예 → 노드선택
             ↓
        Pod 실행
             ↓
      준비 → 서비스갱신
```

| 절차 | 설명 |
|:---|:---|
| 상태선언 | 작업 유형·복제 수·정책을 API에 등록함 |
| 차이조정 | 컨트롤러가 선언 상태와 실제 상태 차이 계산 |
| 노드선택 | 스케줄러가 제약 조건에 맞는 노드를 결정함 |
| Pod실행 | 노드 에이전트가 컨테이너 실행 및 보고 |
| 연결복구 | 준비 상태 반영 및 실패 Pod 교체 |

> 요약: 선언 상태로 Pod를 실행해 서비스에 반영한다.

### 쉽게 이해하기 (학습용)

- 필요한 인원과 조건을 장부에 적고 부족하면 새 일꾼의 자리를 정해 투입하며, 준비된 사람만 안내하고 실패하면 교체하는 순서임

## Ⅴ. 종류 및 비교

| 판단 기준 | Deployment | StatefulSet | DaemonSet |
|:---|:---|:---|:---|
| 식별·저장 | 교체 가능, 외부 상태 관리 | 고정 식별자, 영속 저장소 | 노드별 동일 기능 |
| 배치·복구 | 복제 수·순차 배포 유지 | 순서·식별·연결 유지 | 노드마다 한 Pod 유지 |
| 적용 | 무상태 서비스 | DB 등 순서 필요 작업 | 에이전트 관리 |

> 요약: 배포·상태·노드 상주 특성별 제어기를 쓴다.

### 쉽게 이해하기 (학습용)

- 아무 직원이나 대신할 수 있으면 Deployment, 이름과 개인 사물함이 필요하면 StatefulSet, 모든 지점에 한 명씩 필요하면 DaemonSet임

## Ⅵ. 실무 사례

1. 전자상거래 웹 서비스는 Deployment 복제 Pod를 여러 노드에 분산하고 준비 검사를 통과한 Pod만 Service에 연결함
2. 데이터베이스는 StatefulSet과 영속 저장소를 사용하되 데이터 손상 복구는 별도 백업·복구 절차가 담당함

### 쉽게 이해하기 (학습용)

- 웹 서버는 준비된 복제본으로 자동 교체할 수 있지만, 데이터베이스 파일 자체가 망가진 문제까지 재시작만으로 고칠 수는 없음

## Ⅶ. 결론

- 선언·실제 상태를 맞춰 배치·연결·복구한다

### 쉽게 이해하기 (학습용)

- 원하는 개수와 상태를 적으면 제어기가 계속 맞춰 준다
