## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **청킹(Chunking)**: 문서를 의미가 유지되는 검색 단위로 분할하는 기법이다.
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: 검색 청크를 답변 근거로 제공하는 방식이다.

</details>

- 정의: 원문을 의미가 유지되는 검색 단위로 나누는 **청킹**
- 배경/필요성: 문서 전체를 매 질의마다 입력하면 **문맥 한도 초과•검색 잡음** 비용이 요청마다 반복되므로, 색인 이전에 의미 경계를 보존한 검색 단위로 잘라 두어 필요한 조각만 꺼내 쓰는 계층의 필요

#### 한줄 요약

- 문서를 검색 단위로 분할하고 **출처 정보** 부여

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중첩(Overlap)**: 인접 청크에 경계 문맥을 반복하는 기법이다.
- **메타데이터(Metadata)**: 문서 식별자•위치•계층•인접 관계 정보이다.

</details>

- 문장•문단•절의 의미 구조를 유지하는 **경계 보존**
- 작은 청크는 **검색 정밀도 향상•문맥 단절 증가**
- 큰 청크는 **문맥 보존•검색 잡음 증가**
- 경계와 출처를 보완하는 **중첩•메타데이터**

#### 한줄 요약

- **청크 크기•중첩**에 따른 문맥과 검색 잡음 절충

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **구조 파서(Structure Parser)**: 제목•문단•표•코드 계층을 추출한다.
- **경계 정책기**: 의미 구조의 분할 우선순위를 결정한다.
- **크기 정책**: 청크의 최소•최대 토큰 범위를 정한다.

</details>

```text
[구조 파서]──[경계 정책기]──[크기 정책기]
                    │
             [중첩 정책기]──[메타데이터 기록기]
```

| 구성요소 | 책임 |
|:---|:---|
| 구조 파서 | 제목•문단•표•코드 계층 추출 |
| 경계 정책기 | 의미 구조의 분할 우선순위 결정 |
| 크기 정책기 | 청크 최소•최대 토큰 범위 결정 |
| 중첩 정책기 | 반복할 경계 문맥 결정 |
| 메타데이터 기록기 | 원문 위치•계층•인접 참조 기록 |

#### 한줄 요약

- **경계•크기 정책**과 파서•중첩•메타데이터 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **선택적 중첩(Selective Overlap)**: 필요한 경계 구간에만 중첩을 적용한다.

</details>

```text
구조 파서
   │ 1. 문서 구조•후보 단위 추출
   ▼
청크 정책기
   │ 2. 의미 경계 선택
   │ 3. 크기 조건별 청크 결합
   │ 4. 선택적 중첩•원문 참조 기록
   ▼
메타데이터 기록기
   └── 원문 참조 포함 청크 집합 ──▶ 구조 파서
```

### 동작 원리

1. 문서 구조•후보 단위 추출: 제목•문단•표를 분할 후보로 보존
2. 의미 경계 선택: 구조 우선순위에 따른 절단 지점 결정
3. 크기 조건별 청크 결합: 토큰 상한 안에서 인접 단위 결합
4. 선택적 중첩•원문 참조 기록: 경계 문맥과 위치•계층 보존

#### 한줄 요약

- **구조•크기 조건**에 따른 분할과 중첩•원문 위치 부여

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고정 크기 청킹(Fixed-size Chunking)**: 일정 토큰 수로 문서를 분할한다.
- **구조 기반 청킹(Structure-aware Chunking)**: 문서 계층과 경계를 따라 분할한다.
- **의미 기반 청킹(Semantic Chunking)**: 의미 유사도 변화를 기준으로 분할한다.

</details>

| 구분 | 고정 크기 | 구조 기반 | 의미 기반 |
|:---|:---|:---|:---|
| 적용 기준 | 균일 문서•**빠른 처리** | 명확한 **제목•문단 구조** | **주제 전환 보존** |
| 핵심 특징 | **토큰 수** 기준 분할 | **문서 계층** 기준 분할 | **의미 유사도 변화** 기반 분할 |
| 한계 | **의미 경계 절단** | 불규칙 **구조에 취약** | 계산 비용•**경계 변동** |

#### 한줄 요약

- **문서 구조•의미 변화**와 토큰 수에 따라 경계 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **근거 재현율•정밀도**: 정답 근거의 누락과 검색 잡음을 측정하는 지표이다.
- **추적 가능성(Traceability)**: 청크에서 원문 위치로 되돌아갈 수 있는 성질이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과소•과대한 **청크 크기** | 유형별 **근거 재현율•정밀도** 기반 크기 선택 | 검색 목표에 맞는 **청크 크기 결정** |
| 표•조항•코드의 **의미 경계 절단** | 구조 우선 분할과 선택적 **중첩** 적용 | 근거의 **의미 완결성** 보존 |
| 검색 조각의 **문맥•출처 소실** | **문서 식별자(Identifier, ID)•계층•페이지** 활용 메타데이터로 보존 | 근거의 **추적 가능성** 확보 |

#### 한줄 요약

- **의미 경계•검색 품질**과 원문 추적성 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **선택 기준**: 문서 구조•주제 전환•문맥 보존•중복 비용이다.

</details>

- 정형 문서는 **구조 기반**, 주제 전환이 잦으면 **의미 기반 청킹** 선택

#### 한줄 요약

- **문서 구조•주제 전환 빈도**에 따라 청킹 방식 결정
