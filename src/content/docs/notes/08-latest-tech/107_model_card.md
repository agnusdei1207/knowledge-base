## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 카드(Model Card)**: 모델의 용도•성능•한계•위험을 문서화한 명세서이다.
- **평가 증적(Evaluation Evidence)**: 성능•한계 주장을 뒷받침하는 데이터•지표•시험 결과이다.

</details>

- 정의: 모델 버전의 용도•성능•한계•위험을 기록한 **모델 카드**이다.
- 배경/필요성: 학습된 머신러닝 및 파운데이션 모델이 다양한 다운스트림 애플리케이션과 타 부서/고객에게 배포될 때, 단순한 모델 가중치 파일과 평균 정확도 수치만 공유될 경우, 모델이 훈련된 의도된 사용 용도(Intended Use), 성능이 보장되지 않는 금지된 사용 맥락(Out-of-Scope Use Cases), 인구통계학적 하위 집단별 성능 편차, 알려진 실패 조건 및 편향 한계가 하류 개발자에게 전혀 전달되지 않아 치명적인 오용(Misuse)과 윤리적 사고가 발생하는 근본적 결함에 직면함에 따라, 모델의 개발 목적, 아키텍처, 훈련/평가 데이터셋 분포, 다면적 정량 평가 지표, 윤리적 고려사항 및 실패 사례를 표준화된 단일 문서로 명세화하는 모델 카드(Model Card for Model Reporting / Google Research, Hugging Face, ISO/IEC 42001 Model Transparency) 프레임워크를 도입하여 **모델의 의도된 사용 경계(Application Boundary) 및 금지 맥락의 명확한 사전 고지, 인구통계학적 교차 하위 그룹(Subgroup Disaggregation)별 공정성 및 성능 한계의 투명한 공개, 모델 버전과 평가 증적의 1:1 동시 배포(Co-deployment)를 통한 엔터프라이즈 AI 공급망 투명성 및 책임성 극대화**를 달성할 필요

#### 한줄 요약
- 모델 버전과 **용도•평가 조건•실패 사례** 연결

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적용 경계(Application Boundary)**: 허용 사용자•업무•환경과 금지 맥락 범위이다.
- **잔여 위험(Residual Risk)**: 완화 후에도 남아 판단이 필요한 위험이다.
- **평가 조건(Evaluation Condition)**: 성능 해석에 필요한 데이터•집단•환경•지표이다.

</details>

- 의도한 사용자•용도•금지 맥락의 **적용 경계 명시**
- 데이터•지표•집단별 결과의 **평가 조건 공개**
- 알려진 한계•잔여 위험•관리 책임의 **증적 연결**

#### 한줄 요약
- **적용 경계•평가 조건•잔여 위험•증적** 공개

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **대상 모델 식별(Model Identification)**: 이름•버전•구조를 배포 파일과 연결한다.
- **사용자 범위(User Scope)**: 허용•금지 사용자와 역할 범위이다.
- **문서 수명주기(Document Lifecycle)**: 변경•재평가•승인에 따라 카드를 갱신한다.

</details>

```text
                  [모델 세부정보]
                         |
                    [용도•사용자]
                         |
                  [평가 설계•결과]
                         |
                  [한계•잔여 위험]
                         |
                  [관리•갱신 책임]
```

| 구성요소 | 책임 |
|:---|:---|
| 모델 세부정보 | 이름•버전•구조의 **대상 모델 식별** |
| 용도•사용자 | 권장•금지 업무와 **사용자 범위 정의** |
| 평가 설계•결과 | 데이터•지표•환경별 **성능 증적 제공** |
| 한계•잔여 위험 | 실패 조건과 완화 후 **남은 위험 공개** |
| 관리•갱신 책임 | 승인•변경•재평가의 **문서 수명주기 관리** |

#### 한줄 요약
- **모델 식별•용도•평가•한계•관리 책임** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **승인 문서(Approved Document)**: 주장•증적 일치를 검토해 배포 승인한 버전이다.
- **재평가(Reevaluation)**: 모델•데이터•환경 변경 후 성능•한계를 다시 시험한다.

</details>

```text
┌──────────── 최초 배포•변경 버전마다 ────────────┐
│ 모델 책임자 ── 1. 모델 버전•용도 확정 ──▶ 평가팀
│ 평가팀 ── 2. 평가 증적 생성 ──▶ 카드 작성기   │
│ 카드 작성기 ── 3. 모델 카드 초안 작성 ──▶ 승인자
│ 승인자 ── 4. 주장•증적 검토•승인 ──▶ 카드 작성기
│ 카드 작성기 ── 5. 모델•카드 동시 배포 ──▶ 배포 저장소
└─────────────────────────────────────────────────┘
```

### 동작 원리

1. 모델 버전•용도 확정: 카드와 연결할 **모델•사용 경계** 고정
2. 평가 증적 생성: 데이터•지표•집단별 **검증 결과** 산출
3. 모델 카드 초안 작성: **성능•한계•잔여 위험** 구조화
4. 주장•증적 검토•승인: 카드와 **평가 결과의 일치** 확인
5. 모델•카드 동시 배포: **승인 버전•문서** 공동 게시

#### 한줄 요약
- **버전•평가 증적•카드 작성•승인•동시 배포** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 카드(Data Card)**: 데이터 출처•수집•구성•품질•용도를 기록한다.
- **시스템 카드(System Card)**: 전체 AI 서비스의 구조•안전•운영 통제를 기록한다.

</details>

| 구분 | 모델 카드 | 데이터 카드 | 시스템 카드 |
|:---|:---|:---|:---|
| 적용 기준 | **모델 사용 적합성** | **데이터 사용 적합성** | 전체 서비스의 **잔여 위험** |
| 핵심 특징 | 용도•성능•한계의 **모델 증적** | 출처•수집•품질의 **데이터 증적** | 구조•상호작용•통제의 **시스템 증적** |
| 한계 | **서비스 상호작용** 미포함 | **모델 동작•운영** 미포함 | **작성 범위•검증 비용** 증가 |

#### 한줄 요약
- **모델•데이터•전체 서비스**에 따른 문서 범위 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **버전 불일치(Version Mismatch)**: 배포 모델과 카드 버전이 다른 문제이다.
- **집단별 실패 은폐**: 평균값으로 특정 집단•환경 오류가 가려진 문제이다.
- **증적 단절(Evidence Disconnection)**: 카드 주장과 시험 결과가 연결되지 않은 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모델과 카드의 **버전 불일치** | 모델 파일•카드 버전의 동시 배포 차단 | 잘못된 용도 판단 **방지** |
| 단일 평균값의 **집단별 실패 은폐** | 사용 집단•환경별 성능•오류 분해 | 적용 한계의 **가시성 확보** |
| 주장과 **평가 증적의 단절** | 카드 항목별 데이터•지표•시험 링크 연결 | 문서 신뢰성•감사성 **확보** |

#### 한줄 요약
- **버전•집단별 성능•적용 한계•평가 증적** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동시 배포(Co-deployment)**: 모델과 해당 모델 카드를 한 승인 단위로 제공한다.
- **재발행(Reissue)**: 변경 후 평가•한계를 반영해 카드를 다시 승인•배포한다.

</details>

- 인공지능 모델의 복잡한 기술 사양과 윤리적 한계를 표준화된 명세서로 투명하게 공개하여 책임 있는 AI 배포와 글로벌 AI 거버넌스 규제 준수를 입증하는 **엔터프라이즈 AI 모델 투명성 및 문서화의 핵심 표준(Model Card / Intended Use & Limitations / Subgroup Performance Disaggregation / Dataset & Ethical Considerations / Co-deployment with Model Weights / Alignment with EU AI Act & ISO 42001)의 확고한 표준**으로 확고히 자리 잡았으며, 데이터셋 카드(Dataset Card) 및 시스템 카드(System Card)와 통합된 다층 투명성 생태계로 진화하는 가운데, 실무 모델 카드 운영 시에는 **모델 가중치 파일 릴리스 시 CI/CD 파이프라인에서 모델 카드를 필수 번들링하여 버전 불일치를 원천 차단하고, 단순 평균 정확도가 아닌 취약 계층별 오차율을 상세 분해 공개하며, 운영 중 모델 재학습 및 중대 변경 발생 시 모델 카드를 즉각 갱신·재발행하는 수명주기 관리 체계**를 결합하여 완벽한 문서 추적성과 대외 신뢰성을 완성

#### 한줄 요약
- **문서 대상•변경 범위**에 따라 모델•데이터•시스템 카드 결정
