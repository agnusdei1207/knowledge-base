## 미리 알고가기

- **모델 카드**: 모델 용도, 데이터, 성능, 한계를 공개하는 구조적 문서
- **README**: README가 개발 실행 정보를 다룬다면 모델 카드는 사용 적합성을 다룸
- **버전 갱신**: 모델 버전과 함께 갱신되어 배포 시 함께 제공 필요



## Ⅰ. 개요

- **정의/개념**: 모델 용도·평가·성능·한계를 기록한 문서
- **배경/필요성**: 적용 범위와 실패 조건을 버전별로 전달

### 쉽게 이해하기 (학습용)

- 모델 설명서에 권장 용도뿐 아니라 평가 조건과 금지 용도, 알려진 한계를 함께 적습니다.

## Ⅱ. 특징

- 의도한 용도와 금지 맥락을 명시해 오용을 줄인다.
- 평가 조건과 집단별 성능으로 편차를 드러낸다.
- 알려진 한계·윤리 고려사항으로 추가 검증을 유도한다.
- 문서 존재와 실제 안전성은 별도로 검증해야 한다.

### 쉽게 이해하기 (학습용)

- 설명서의 안전 주장과 실제 검증은 다르므로 평가 결과와 승인 기록을 별도로 확인해야 합니다.

## Ⅲ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 세부정보 | 이름, 버전, 개발사, 구조 식별 |
| 용도/사용자 | 허용 업무 및 금지 맥락 명시 |
| 평가설계 | 데이터, 지표, 검증 환경 정의 |
| 성능결과 | 조건별 결과 및 오류 분석 해석 |
| 한계/관리 | 실패 케이스, 위험 완화, 갱신 책임 |

```text
                  [모델 세부정보]
                         │
[의도한 용도·사용자] ─ [모델 카드] ─ [평가 조건·성능 결과]
                         │
                 [한계·윤리·관리]
```

### 쉽게 이해하기 (학습용)

- 모델 버전·사용자·용도·평가 결과·한계·관리 책임을 한 문서에 연결합니다.

## Ⅳ. 원리 및 절차 흐름도

```text
버전확정 → 평가설계 → 증적수집 → 검토배포 → 갱신관리
```

| 절차 | 설명 |
|:---|:---|
| 버전확정 | 분석 대상 모델과 용도 고정함 |
| 평가설계 | 맥락별 데이터, 집단, 지표 정의함 |
| 증적수집 | 성능 오류 및 한계 통제 작성함 |
| 검토배포 | 사실 확인 후 모델에 연결 배포함 |
| 갱신관리 | 환경 변경 시 재평가 후 카드 발행함 |

### 쉽게 이해하기 (학습용)

- 모델 버전과 용도를 고정해 평가하고 승인한 뒤 모델이나 환경이 바뀌면 카드도 갱신합니다.

## Ⅴ. 종류 및 비교

| 적용 기준 | 모델 카드 | 데이터 카드 | 시스템 카드 |
|:---|:---|:---|:---|
| 기록대상 | 학습된 모델과 버전 | 데이터셋 및 출처 | 전체 AI 서비스 시스템 |
| 핵심증적 | 용도, 성능, 한계 정보 | 수집, 품질, 가공 정보 | 구조, 상호작용, 안전 운영 |
| 적용기준 | 모델 적합성 판단 | 데이터 사용 적합성 판단 | 서비스 잔여 위험 판단 |

> 요약: 모델·데이터의 사용 적합성 판단 근거를 기록한다.

### 쉽게 이해하기 (학습용)

- 모델 카드는 모델, 데이터 카드는 데이터셋, 시스템 카드는 전체 서비스와 운영의 설명서입니다.

## Ⅵ. 실무 사례

- 저장소는 모델과 같은 버전의 카드만 배포한다.
- 모델·가드레일이 바뀌면 카드와 평가를 갱신한다.

### 쉽게 이해하기 (학습용)

- 모델과 카드 버전이 다르면 배포하지 않고 새 버전의 평가 결과와 한계를 다시 연결합니다.

## Ⅶ. 결론

- 모델 버전과 평가·한계를 연결해 배포 판단에 쓴다.

### 쉽게 이해하기 (학습용)

- 모델 카드는 사용 적합성의 근거를 주지만 문서가 있다는 사실만으로 안전성을 보장하지는 않습니다.
