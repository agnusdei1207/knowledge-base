## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 호스트와 외부 서버가 도구•리소스•프롬프트를 발견하고 교환하는 메시지를 표준화한 연결 프로토콜로 정의된다.

</details>

- 정의/개념: **MCP**는 AI 호스트와 외부 서버가 JSON-RPC로 도구•리소스•프롬프트를 발견하고 사용하는 연결 프로토콜임.
- 배경/필요성: 서버마다 맞춤 연동을 구현하면 기능 발견•메시지 처리 로직이 중복되고 호환성이 저하된음.

#### 한줄 요약
- **MCP**의 공통 메시지와 기능 발견으로 서버별 중복 연동을 줄인다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **요청 자기기술성**: 각 요청이 프로토콜 버전•클라이언트 식별•기능을 자체 메타데이터로 전달하는 성질이다.
- **서버 발견(server/discover)**: 클라이언트가 호출 전에 서버 기능을 선택적으로 조회하는 원격 절차 호출을 말한다.
- **자바스크립트 객체 표기법 원격 절차 호출(JavaScript Object Notation Remote Procedure Call, JSON-RPC)**: 요청•응답•알림•오류를 JSON 객체로 표현하는 메시지 형식을 의미한다.
- **무상태 축**: 요청마다 버전•식별•기능 메타데이터를 전달하는 기능 영역을 의미한다.
- **메시지 축**: JSON-RPC로 도구•리소스•프롬프트를 교환하는 기능 영역을 의미한다.
- **책임 축**: 호스트•클라이언트•서버의 정책•연결•기능 책임을 구분하는 기능 영역을 말한다.

</details>

- **무상태 축**: 요청별 버전•식별•기능을 담는 자기기술 메시지임.
- **메시지 축**: **JSON-RPC**를 기반으로 도구•리소스•프롬프트를 교환함.
- **책임 축**: 호스트•클라이언트•서버의 정책•연결•기능을 분리함.

#### 한줄 요약
- **요청 자기기술성**과 **서버 발견**으로 서버 연동 방식을 통일한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜 호스트(Model Context Protocol Host, MCP Host)**: 사용자 동의•보안 정책과 여러 MCP 클라이언트 연결을 관리하는 인공지능 애플리케이션을 의미한다.
- **MCP 클라이언트(MCP Client)**: 서버별 연결과 프로토콜 메시지 교환을 관리하는 호스트 내부 구성요소이다.
- **MCP 서버(MCP Server)**: 도구•리소스•프롬프트 기능을 표준 메시지로 제공하는 외부 구성요소을 말한다.
- **표준 입출력(Standard Input/Output, stdio)**: 로컬 MCP 프로세스가 표준 입력•출력 스트림으로 메시지를 교환하는 전송 방식이다.
- **스트리밍 가능 HTTP(Streamable Hypertext Transfer Protocol, Streamable HTTP)**: HTTP POST와 요청 라우팅 헤더로 원격 MCP 메시지를 교환하는 방식이다.

</details>

```text
                  [MCP 호스트]
                       |
                [MCP 클라이언트]
                       |
                  [MCP 서버]
                       |
             [JSON-RPC•전송 계층]
```

선의 의미: MCP 호스트 내부의 클라이언트가 MCP 서버와 연결되고, JSON-RPC•전송 계층이 양측 메시지 교환 경계를 제공하는 프로토콜 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| MCP 호스트 | **MCP Host**가 사용자 동의•정책•복수 서버 연결 관리 |
| MCP 클라이언트 | **MCP Client**가 서버별 연결•메시지 교환 관리 |
| MCP 서버 | **MCP Server**가 도구•리소스•프롬프트 제공 |
| JSON-RPC•전송 계층 | **JSON-RPC**를 **stdio** 또는 **Streamable HTTP**로 전달 |

#### 한줄 요약
- **MCP Host**가 서버별 클라이언트 연결과 보안 경계를 관리한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **무상태 코어**: 초기화 핸드셰이크와 프로토콜 세션 없이 각 요청이 필요한 메타데이터를 전달하는 구조을 말한다.
- **캐시 힌트**: 목록•리소스 응답의 유지 시간과 공유 범위를 알려 재조회 비용을 줄이는 정보을 의미한다.
- **버전•클라이언트 메타 포함 요청**: 요청마다 프로토콜 버전•식별•기능을 전달하는 단계로 정의된다.
- **서버 기능 발견 요청**: 필요할 때 서버의 기능 목록과 확장을 조회하는 단계이다.
- **서버 기능 발견 결과 제공**: 사용 가능한 서버 기능과 확장을 클라이언트에 반환하는 단계로 정의된다.
- **원시 기능 목록•선택 기능 호출 요청**: 목록을 조회한 뒤 도구 호출•리소스 읽기를 수행하는 단계로 정의된다.
- **캐시 힌트•기능 결과 응답**: 유지 시간•공유 범위와 실행 결과•오류를 반환하는 단계로 정의된다.

</details>

```text
MCP 클라이언트
   │ 1. 버전•클라이언트 메타 포함 요청
   ├──────────────────────┐
   │ 사전 발견이 필요하면 │
   └──────────┬───────────┘
   │ 2. 서버 기능 발견 요청
   ▼
MCP 서버
   │ 3. 서버 기능 발견 결과 제공
   ▼
MCP 클라이언트
   │ 4. 원시 기능 목록•선택 기능 호출 요청
   ▼
MCP 서버
   │ 5. 캐시 힌트•기능 결과 응답
   ▼
MCP 클라이언트
```

### 동작 원리

1. **버전•클라이언트 메타 포함 요청**: **무상태 코어**에서 요청마다 프로토콜 버전•식별•기능을 전달함.
2. **서버 기능 발견 요청**: 필요하면 **server/discover**로 기능을 조회함.
3. **서버 기능 발견 결과 제공**: 사용 가능한 서버 기능과 확장을 반환함.
4. **원시 기능 목록•선택 기능 호출 요청**: 목록 조회 후 도구 호출•리소스 읽기를 수행함.
5. **캐시 힌트•기능 결과 응답**: **캐시 힌트**의 TTL•공유 범위와 실행 결과•오류를 반환함.

#### 한줄 요약
- **버전•클라이언트 메타 포함 요청**과 **서버 기능 발견 요청** 후 기능을 호출한다.


## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **개방형 응용 프로그래밍 인터페이스 명세(OpenAPI Specification, OpenAPI)**: 고정된 하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol, HTTP) API 계약을 기술하는 명세을 의미한다.

</details>

| 판단 기준 | MCP | OpenAPI | 맞춤형 API |
|:---|:---|:---|:---|
| 적용 기준 | **MCP**는 모델의 도구•컨텍스트 선택 | **OpenAPI**는 고정 HTTP 계약 | 맞춤형 API는 단일 시스템 연동 |
| 핵심 특징 | 기능 발견•호출•컨텍스트 교환 | HTTP API 계약 기술 | 구현별 직접 연동 |
| 한계 | 호스트•서버 보안 구현 필요 | 동적 기능 발견 없음 | 재사용•상호운용성 부족 |

> 요약: **MCP**는 기능 발견, **OpenAPI**는 고정 HTTP 계약에 초점을 둔다.

#### 한줄 요약
- 기능 발견•컨텍스트 교환은 **MCP**, 고정 계약은 **OpenAPI**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **신뢰 경계**: 호스트•클라이언트•서버 사이에서 인증•권한•입력 검증 책임이 달라지는 보안 경계을 말한다.
- **전송 계층 보안(Transport Layer Security, TLS)**: 원격 전송 메시지의 기밀성•무결성과 서버 인증을 제공하는 보안 프로토콜이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 기능 공개로 생기는 권한 확산 | **신뢰 경계**별 허용 목록•최소 권한 적용 | 서버 간 보안 경계 유지 |
| 원격 전송의 인증 토큰 탈취•오용 | **TLS**와 토큰 대상•범위•재사용 탐지 적용 | 비인가 요청과 권한 오용 방지 |
| 도구 호출의 실제 업무 부작용 | 호스트가 동의•인자•대상•승인 검증 | 연결과 실행 권한 분리 |

#### 한줄 요약
- 서버별 **신뢰 경계**와 최소 권한•허용 목록으로 기능 공개 범위를 제한한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **MCP 적용 구분**: AI 호스트가 모델의 기능 발견•컨텍스트 교환이 필요할 때 MCP를 적용하고, 고정 HTTP 계약만 필요하면 OpenAPI를 적용하는 구분을 의미한다.

</details>

- **MCP 적용 구분**에 따라 기능 발견과 요청별 메타데이터가 필요하면 **MCP**, 고정 HTTP 계약만 필요하면 **OpenAPI**를 선택함.

#### 한줄 요약
- **MCP 적용 구분**과 서버별 최소 권한을 함께 적용한다.
