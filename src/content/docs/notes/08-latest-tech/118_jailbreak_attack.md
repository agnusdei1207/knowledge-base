## 미리 알고가기

- **탈옥 공격**: 모델의 안전 정책과 거부 규칙을 우회해 금지된 출력을 유도하는 공격
- **역할극**: 역할극·인코딩·다단계 대화 등 언어적 우회 수단 활용
- **과잉 거부**: 차단 강화 시 정상 질문까지 막는 오버 리퓨절(Over-refusal) 발생



## Ⅰ. 개요

- **정의/개념**: 안전 정책을 우회해 금지 행동을 유도하는 공격이다
- **배경/필요성**: 변형되는 우회와 과잉 거부를 함께 줄인다

### 쉽게 이해하기 (학습용)
- 질문을 소설 설정이나 암호문으로 바꿔 AI의 거부 정책을 회피한다.

## Ⅱ. 특징

- 안전 거부 우회는 금지 응답·기능 오용을 만든다
- 역할극·인코딩·다단계 조합은 탐지를 어렵게 한다
- 정책 노출은 표현을 바꾼 적응형 공격을 늘린다
- 높은 차단 임계값은 정상 요청의 과잉 거부를 만든다
- 공격·정상 회귀는 안전성과 사용성 저하를 함께 막는다

### 쉽게 이해하기 (학습용)
- 방어 규칙에 맞춰 표현을 바꾸는 공격과 정상 질문의 과잉 거부를 함께 평가해야 한다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 안전 정책 | 금지·허용 범위와 예외 처리 기준 |
| 정렬 모델 | 정책에 맞는 응답과 거부 생성 |
| 판정기 | 적대적 의도와 정책 위반 독립 분류 |
| 권한 게이트 | 호출 전 행위 결정적 승인·거부 |
| 평가 체계 | 공격·정상 요청의 결과 축적 평가 |

> 요약: 정책·판정·권한·평가를 분리해 우회를 통제한다

### 쉽게 이해하기 (학습용)
- 모델의 거절 습관에만 의존하지 않고 독립 검사와 도구 권한 확인을 수행한다.

## Ⅳ. 원리 및 절차 흐름도

```text
공격+정상 데이터 → 응답 생성
           ↓
독립·권한 검증 → 결과 분류
           ↓
사례 갱신 ⟵ 성공·과잉 거부 ⟷ 정상 통과
```

| 절차 | 설명 |
|:---|:---|
| 입력 구성 | 역할극·난독화로 우회 프롬프트 생성 |
| 정책 판정 | 의도와 내용을 허용 여부에 매핑 |
| 응답 생성 | 답변이나 도구 호출 계획 생성 |
| 독립 검증 | 정책 위반 여부 최종 판정 |
| 회귀 평가 | 성공과 과잉 거부 사례 반영 |

> 요약: 우회·정상 입력을 검증해 정책과 회귀 세트를 갱신한다

### 쉽게 이해하기 (학습용)
- 새 우회 질문과 정상 질문을 함께 검증해 공격 성공과 과잉 거부를 회귀 세트에 반영한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 탈옥 공격 | 인젝션 |
|:---|:---|:---|
| 공격 목표 | 정책 우회 후 유해 콘텐츠 유도 | 업무 지시 변경 후 흐름 탈취 |
| 영향 경로 | 대화로 모델 거부 정책 직접 공략 | 입력·외부 콘텐츠로 흐름 변경 |
| 적용 기준 | 의도와 정책 위반 단계 판정 | 지시 출처와 요청 권한 정합 판정 |

> 요약: 탈옥은 정책, 인젝션은 업무 지시를 바꾼다

### 쉽게 이해하기 (학습용)
- 탈옥은 금지된 답변을 유도하고 인젝션은 업무 지시와 실행 흐름을 바꾼다.

## Ⅵ. 실무 사례

1. 코드 서비스는 생성·분석 요청과 실행 권한을 구분한다
2. 챗봇은 탈옥·정상 세트로 차단 임계값을 조정한다

### 쉽게 이해하기 (학습용)

- 같은 보안 용어라도 공격 코드 제작과 방어 분석은 목적이 다르므로 답변과 실행 권한을 나눠 판단한다.
- 탈옥과 정상 문의를 함께 반복해 공격 성공률과 과잉 거부율의 균형을 조정한다.

## Ⅶ. 결론

- 적응형 공격과 정상 요청을 독립 정책으로 회귀 검증한다.

### 쉽게 이해하기 (학습용)

- 모든 우회 문장을 미리 막기보다 정상 질문과 함께 검증해 안전성과 사용성을 유지한다.
