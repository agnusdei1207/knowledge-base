## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜 리소스(Model Context Protocol Resource, MCP Resource)**: 서버가 URI로 식별하여 클라이언트에 읽기 중심의 컨텍스트 데이터를 제공하는 MCP 기능이다.
- **통합 자원 식별자(Uniform Resource Identifier, URI)**: 리소스를 고유하게 가리키는 주소 표기이다.

</details>

- 정의/개념: **URI** 기반 읽기 문맥을 제공하는 **MCP Resource**이다.
- 배경/필요성: 파일•데이터별 탐색•조회 방식 차이로 컨텍스트를 재사용하기 어렵다.

#### 한줄 요약
- **URI**로 필요한 읽기 문맥을 식별•조회가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **애플리케이션 제어 컨텍스트**: 호스트가 리소스를 조회하고 모델 문맥에 포함할지 결정하여 데이터 사용 범위를 통제하는 방식이다.
- **변경 알림 구독**: subscriptions/listen 스트림에서 선택한 리소스 변경 알림을 받는 기능이다.
- **제어 축**: 애플리케이션이 조회와 모델 문맥 포함 여부를 결정하는 기능 영역이다.
- **식별 축**: URI와 URI Template로 컨텍스트를 식별하는 기능 영역이다.
- **최신성 축**: 변경 알림 구독으로 선택 리소스의 갱신을 추적하는 기능 영역이다.

</details>

- **제어 축**: **애플리케이션 제어 컨텍스트**로 조회•모델 문맥 포함을 결정한다.
- **식별 축**: **URI•URI Template** 기반 컨텍스트 식별이다.
- **최신성 축**: subscriptions/listen 기반 변경 알림을 전달한다.

#### 한줄 요약
- **URI•MIME**으로 자료를 읽고 선택한 변경 알림 수신이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **통합 자원 식별자 템플릿(Uniform Resource Identifier Template, URI Template)**: 변수 자리를 포함해 여러 관련 리소스의 URI를 생성하는 주소 규칙이다.
- **다목적 인터넷 우편 확장 형식(Multipurpose Internet Mail Extensions Type, MIME Type)**: 리소스 내용의 데이터 유형과 해석 방식을 나타내는 표기이다.
- **자바스크립트 객체 표기법 원격 절차 호출(JavaScript Object Notation Remote Procedure Call, JSON-RPC)**: 리소스 조회 요청과 결과를 교환하는 메시지 형식이다.

</details>

- **URI Template•MIME Type•JSON-RPC** 기반으로 리소스를 식별하고 반환한다.

```text
                       [리소스 명세]
                      /       |       \
             [URI 템플릿] [내용 제공기] [변경 알림 관리자]
```

선의 의미: 리소스 명세는 URI 템플릿, 내용 제공기, 변경 알림 관리자의 공통 계약이다.

| 구성요소 | 책임 |
|:---|:---|
| 리소스 명세 | **URI**•이름•**MIME Type** 정보 제공 |
| URI 템플릿 | **URI Template**로 리소스 범위 표현 |
| 내용 제공기 | **JSON-RPC** 기반 URI 콘텐츠 반환 |
| 변경 알림 관리자 | **변경 알림 구독** 관리 |

#### 한줄 요약
- **리소스 명세•내용•변경 알림**을 URI로 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **리소스 읽기**: 클라이언트가 URI를 지정하고 서버가 MIME 형식과 함께 텍스트 또는 바이너리 내용을 반환하는 요청 흐름이다.
- **모델 컨텍스트 프로토콜 클라이언트(Model Context Protocol Client, MCP Client)**: 서버와 리소스 명세•내용을 교환하는 구성요소이다.
- **모델 컨텍스트 프로토콜 서버(Model Context Protocol Server, MCP Server)**: 권한 범위의 리소스 명세와 내용을 제공하는 구성요소이다.
- **리소스 목록•템플릿 요청**: 권한 범위의 URI와 템플릿을 조회하는 단계이다.
- **URI 읽기 요청**: 선택한 리소스의 텍스트•바이너리 내용을 요구하는 단계이다.
- **URI 해석•권한 검증 후 내용 반환**: URI와 테넌트 권한을 확인해 MIME 정보와 내용을 제공하는 단계이다.
- **변경 알림 구독 등록**: 선택한 리소스의 갱신 알림 유형을 등록하는 단계이다.
- **구독 리소스 변경 알림**: 변경 URI의 재조회 필요성을 클라이언트에 알리는 단계이다.

</details>

- **MCP Client** 요청은 **MCP Server**가 **URI** 권한을 확인한 뒤 **MIME Type** 정보와 내용으로 반환한다.

```text
MCP 클라이언트
   │ 1. 리소스 목록•템플릿 요청
   ▼
MCP 서버
   │ 권한 범위의 URI 명세 반환
   ▼
MCP 클라이언트
   │ 2. URI 읽기 요청
   ▼
MCP 서버
   │ 3. URI 해석•권한 검증 후 내용 반환
   ▼
MCP 클라이언트
   │ 4. 변경 알림 구독 등록
   ▼
MCP 서버
   ├──────────────────────┐
   │ 구독 리소스 변경 시  │
   └──────────┬───────────┘
   │ 5. 구독 리소스 변경 알림
   ▼
MCP 클라이언트
```

### 동작 원리

1. **리소스 목록•템플릿 요청**: 권한 범위의 URI•템플릿을 조회한다.
2. **URI 읽기 요청**: **리소스 읽기**로 선택한 텍스트•바이너리 내용을 요구한다.
3. **URI 해석•권한 검증 후 내용 반환**: MIME과 검증된 내용을 제공한다.
4. **변경 알림 구독 등록**: subscriptions/listen에서 알림 유형을 선택한다.
5. **구독 리소스 변경 알림**: 변경된 URI의 재조회 필요성을 통지한다.

#### 한줄 요약
- **URI 읽기 요청**과 **구독 리소스 변경 알림**으로 필요한 문맥만 최신화한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **직접 리소스**: 고정 URI 하나로 특정 파일•레코드•문서 같은 컨텍스트를 식별해 제공하는 리소스 유형이다.
- **도구(Tool)**: 모델이 외부 기능을 실행하도록 호출하는 MCP 기능이다.
- **프롬프트(Prompt)**: 사용자가 선택해 재사용할 수 있는 메시지•작업 틀을 제공하는 MCP 기능이다.

</details>

- **MCP Resource•Tool•Prompt**를 문맥 조회•행동 실행•작업 틀 제공 기준으로 구분한다.

| 비교 기준 | Resource | Tool | Prompt |
|:---|:---|:---|:---|
| 적용 기준 | **Resource**는 문맥 데이터 제공 | **Tool**은 외부 기능 실행 | **Prompt**는 사용자 작업 틀 제공 |
| 핵심 특징 | 앱 제어•URI 조회 | 모델 제어•스키마 호출 | 사용자 제어•메시지 생성 |
| 한계 | 직접 행동 수행 불가 | 부작용•권한 위험 | 사용자 선택•입력 필요 |

> 요약: 문맥 조회에는 **Resource**, 행동에는 **Tool**, 작업 틀에는 **Prompt**을 적용한다.

#### 한줄 요약
- **직접 리소스**는 고정 URI 문맥에 사용하고 행동 실행은 **Tool**을 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **변경 알림 갱신**: 구독한 변경 알림을 받아 필요한 리소스만 재조회하는 운영 방식이다.
- **리소스 통제 원칙**: URI 기반 문맥 제공 시 템플릿•테넌트•목적별 최소 필드로 노출 범위를 통제하는 원칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| URI 조작으로 범위 밖 조회 | **리소스 통제 원칙**에 따라 템플릿•테넌트 권한 재검증 | 경로•테넌트 우회 방지 |
| 과다 제공으로 문맥 오염•정보 노출 | 목적별 분할•최소 필드 적용 | 문맥 품질•기밀성 확보 |
| 빈번한 변경으로 최신성 저하 | **변경 알림 갱신**으로 필요한 URI만 재조회 | 최신성 확보•트래픽 감소 |

#### 한줄 요약
- **URI•테넌트 권한**을 검증해 교차 자료 접근 차단이 핵심이다.
