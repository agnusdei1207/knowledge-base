## 미리 알고가기

- **Delta Lake**: Parquet 파일과 트랜잭션 로그를 결합한 테이블 관리 기술
- **트랜잭션 로그**: 파일의 입고·제외·규칙을 기록해 테이블 상태를 재구성하는 핵심 파일
- **ACID**: 테이블의 읽기·쓰기 시 원자성, 일관성, 고립성, 지속성을 보장함
- **시간 여행**: 과거 특정 버전의 스냅샷으로 돌아가 데이터를 조회하는 기능
- **스키마 관리**: 데이터 쓰기 시 스키마 정합성을 검사하고 변경사항을 적용함
- **최적화**: 체크포인트 및 파일 병합으로 로그 재생 및 조회 성능을 유지함



## Ⅰ. 개요

데이터 파일과 트랜잭션 로그를 결합해 버전 관리와 트랜잭션을 제공함

- **정의/개념**: 트랜잭션 로그 기반 오픈 테이블 형식
- **배경/필요성**: 데이터 레이크의 동시 쓰기·스키마를 통제
### 쉽게 이해하기 (학습용)

- **데이터 관리**: 변경 추적, 스키마 관리, 과거 상태 재현 가능

## Ⅱ. 특징

- 트랜잭션 로그가 파일 집합 상태를 재구성한다.
- 체크포인트가 장기 로그 재생 비용을 줄인다.
- 낙관적 동시성이 충돌 커밋을 차단한다.
- 스키마 통제·시간 여행이 변경 추적을 돕는다.

### 쉽게 이해하기 (학습용)

- 장부를 요약한 중간 결산표에서 이후 거래만 더하면 빠르게 재고를 알 수 있지만 폐기된 옛 물건까지 되살릴 수는 없음

## Ⅲ. 아키텍처 및 구성요소

```text
[_delta_log checkpoint @ N] + [commit N+1 ... M]
                    │ replay actions
                    ▼
          [Snapshot M: schema + active files]
                    │
                    ▼
              [Parquet Data Files]
```

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 파일 | 행 데이터를 열 지향 파일에 저장함 |
| 순차 로그 | 버전별 프로토콜·데이터 동작 기록 |
| 체크포인트 | 상태 요약으로 전체 로그 재생 방지 |
| 충돌 검증기 | 작업 충돌 여부 검사 후 로그 게시 |
| 프로토콜 | 버전·테이블 기능 호환성 관리 |

> 요약: 체크포인트·로그로 유효 파일과 상태 재구성

### 쉽게 이해하기 (학습용)

- 마지막 결산표와 그 뒤 거래 장부를 합쳐야 현재 재고가 나오며 창고에 남아 있는 상자만 세면 제외된 파일까지 잘못 포함할 수 있음

## Ⅳ. 원리 및 절차 흐름도


```text
기준상태확인
     ↓
데이터파일작성
     ↓
충돌검증
     ↓
로그커밋
     ↓
스냅샷공개
```

| 절차 | 설명 |
|:---|:---|
| 1. 상태확인 | 체크포인트와 로그로 기준 스냅샷 확인함 |
| 2. 파일작성 | 변경된 데이터를 새 데이터 파일로 생성함 |
| 3. 충돌검증 | 동시 변경 작업과 충돌 여부를 검사함 |
| 4. 로그커밋 | 충돌 없으면 새 로그 버전을 원자적 기록 |
| 5. 스냅샷공개 | 커밋 성공 시 새 버전 스냅샷 공개함 |

> 요약: 파일 작성 후 충돌 검증을 거쳐 원자적으로 로그를 게시함

### 쉽게 이해하기 (학습용)

- 새 물건을 준비한 뒤 다른 담당자가 장부를 바꿨는지 확인하고 충돌이 없을 때만 다음 장부 번호로 거래를 확정함

## Ⅴ. 종류 및 비교

| 판단 기준 | Delta Lake | Apache Iceberg | Apache Hudi |
|:---|:---|:---|:---|
| 핵심 특징 | 순차 커밋 로그와 체크포인트로 스냅샷을 재구성함 | 메타데이터 파일·스냅샷·매니페스트 트리를 원자 교체함 | 타임라인과 파일 그룹·테이블 서비스로 상태를 관리함 |
| 적용 기준 | 기준 스냅샷 이후 변경을 검증해 새 로그 버전을 커밋함 | 새 메타데이터 포인터를 원자 교체하고 충돌 시 재시도함 | 동시성 모드와 잠금·충돌 해소 설정에 따라 커밋함 |
| 주요 위험 | 로그 기반 변경 추적·스키마·배치/스트리밍 연계가 중요함 | 대규모 계획·파티션 진화·다중 엔진 공유가 중요함 | 증분 처리·업서트·내장 파일 서비스가 중요함 |

> 요약: 엔진별 Delta 프로토콜·기능 지원 확인

### 쉽게 이해하기 (학습용)

- 같은 창고 관리 목적이라도 Delta는 거래 장부, Iceberg는 버전별 목록 트리, Hudi는 작업 시간표와 파일 묶음을 중심으로 관리함
