## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **전문가 혼합(Mixture of Experts, MoE)**: 라우터가 토큰별로 다수 전문가 중 일부만 활성화하는 조건부 계산 신경망 구조다.
- **조건부 계산**: 입력에 선택된 일부 매개변수만 실행하여 전체 모델 용량과 활성 연산량을 분리하는 방식이다.

</details>

- 정의/개념: **MoE**는 라우터가 토큰별 일부 전문가를 선택하는 조건부 계산 신경망 구조이다.
- 배경/필요성: 밀집 모델의 모든 매개변수 활성화로 **연산량•전력 비용** 급증이 발생한다.

#### 한줄 요약
- **Top-k 라우팅•부하 균형** 기반 조건부를 계산한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **Top-k 라우팅**: 라우터 점수가 높은 k개 전문가를 토큰별로 선택하는 방식이다.
- **부하 균형 손실**: 토큰이 특정 전문가에 몰리지 않도록 라우팅 분포를 고르게 유도하는 학습 항이다.
- **초과 토큰 정책**: 전문가 용량을 넘은 토큰을 버리거나 다른 전문가로 보내는 처리 규칙이다.

</details>

- **라우터의 Top-k 점수**에 따른 활성 전문가•결합 가중치를 결정한다.
- **부하 균형 손실•초과 토큰 정책** 기반 전문가 용량 쏠림을 통제한다.
- 희소 활성화에도 필요한 **전체 가중치 저장•장치 간 통신**이 핵심이다.

#### 한줄 요약
- 희소 활성에도 **전체 가중치•All-to-All 통신** 필요가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **순방향 신경망(Feed-Forward Network, FFN) 전문가**: 토큰별 비선형 변환을 수행하며 다른 전문가와 독립된 매개변수를 가진 블록이다.
- **Top-k 라우터(Top-k Router)**: 토큰별 전문가 점수를 계산하고 가장 높은 일부 전문가와 결합 가중치를 선택한다.
- **디스패처**: 라우터 선택에 따라 토큰을 해당 전문가가 있는 장치로 전송한다.
- **부하 제어기**: 특정 전문가로 토큰이 몰리지 않도록 보조 손실•용량 제한•드롭 정책을 적용한다.
- **결합기**: 전문가 출력을 라우팅 가중치로 합치고 원래 토큰 순서를 복원한다.

</details>

```text
                     [부하 제어기]
                       /       \
[Top-k 라우터] ----- [디스패처] ----- [전문가 블록] ----- [결합기]
```

선의 의미: Top-k 라우터, 디스패처, 전문가 블록, 결합기는 희소 전문가 계산의 정적 데이터 경로를 이루고, 부하 제어기는 디스패처와 전문가 블록의 용량•쏠림 경계를 함께 통제하는 MoE 네트워크를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| Top-k 라우터 | **전문가 점수•결합 가중치** 계산 |
| 디스패처 | **선택 전문가 토큰 전송** |
| 전문가 블록 | 독립적인 **FFN 변환** 수행 |
| 부하 제어기 | **용량•쏠림•초과 토큰** 통제 |
| 결합기 | **출력 가중 결합•순서 복원** |

#### 한줄 요약

- **라우터•디스패처•전문가•부하 제어•결합기**를 구성한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **라우팅 확률**: 각 토큰이 전문가별로 배정될 적합도를 나타내는 점수 분포다.
- **전체 상호 통신(All-to-All)**: 각 장치가 다른 모든 장치와 전문가 입력•출력 토큰을 교환하는 통신이다.

</details>

```text
라우터
   │ 1. 전문가 점수 산출
   ▼
부하 제어기
   │ 2. Top-k•용량 판정
   ▼
라우터
   │ 3. 토큰 분배
   ▼
전문가군
   │ 4. 선택 전문가 계산
   ▼
결합기
   │ 5. 출력 결합•순서 복원
   ▼
출력
```

**동작 원리**

1. **전문가 점수 산출**: 토큰별 **라우팅 확률**을 계산한다.
2. **Top-k•용량 판정**: 활성 전문가와 **초과 정책**을 결정한다.
3. **토큰 분배**: All-to-All 기반 **전문가 전송**한다.
4. **선택 전문가 계산**: 활성화된 **FFN만을 연산**한다.
5. **출력 결합•순서 복원**: 라우팅 가중합과 **토큰을 재배열**한다.
#### 한줄 요약

- **점수•Top-k•분배•전문가 계산•결합**을 수행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **밀집 순방향 신경망(Feed-Forward Network, FFN)**: 모든 토큰이 같은 순방향 신경망 전체를 실행하여 구조는 단순하지만 활성 연산량이 크다.
- **Top-1 MoE**: 토큰마다 전문가 하나만 활성화해 연산을 최소화하는 방식이다.
- **Top-k MoE**: 복수 전문가 출력을 결합해 표현력을 높이는 방식이다.

</details>

밀집 FFN과 MoE는 토큰당 활성화하는 매개변수 범위가 다르다.

| 토큰 활성화 구조 | 밀집 FFN | Top-1 MoE | Top-k MoE |
|:---|:---|:---|:---|
| 적용 기준 | **단순 실행•작은 모델** | **최소 활성 연산 우선** | **복수 전문가 결합 필요** |
| 핵심 특징 | 모든 토큰의 **동일 FFN 실행** | 토큰당 **전문가 1개 활성화** | 토큰당 **전문가 k개 활성화** |
| 한계 | **활성 연산량 증가** | **쏠림•용량 초과** | **통신•결합 비용 증가** |

#### 한줄 요약

- **활성 연산량•전문가 결합 범위**로 구조를 구분한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **라우팅 쏠림**: 토큰이 일부 전문가에 집중되어 다른 전문가는 놀고 병목이 발생하는 현상이다.
- **전문가 붕괴**: 일부 전문가만 유용한 기능을 학습하고 나머지 전문가의 품질이 떨어지는 현상이다.
- **용량 계수**: 전문가가 한 배치에서 수용할 수 있는 토큰 수를 평균 배정량 대비 비율로 정한 값이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **라우팅 쏠림** | **부하 균형 손실**•토큰 수 감시 | 전문가 활용 **균등화** |
| **용량 초과** | 용량 계수•**초과 토큰 정책** 설정 | 토큰 손실•지연 **통제** |
| **통신 병목** | 전문가 배치•**All-to-All** 최적화 | 장치 대기 **감소** |
| **전문가 붕괴** | 라우팅 분포•**전문가 품질** 추적 | 기능 편중 **조기 탐지** |

#### 한줄 요약
- **전문가별 토큰 수•통신 시간**으로 쏠림 탐지가 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **전문가 혼합 선택 기준**: 희소 활성화의 연산 절감이 부하 균형과 장치 간 통신 비용보다 클 때 적용한다.
- **밀집 순방향 신경망 선택 기준**: 모델 규모가 작거나 단순 실행과 안정적인 지연이 더 중요할 때 적용한다.

</details>
- 희소 활성 이득이 통신 비용보다 크면 **MoE**, 작으면 **밀집 FFN**을 선택한다.

#### 한줄 요약
- **희소 활성 이득•통신 비용**에 따라 MoE•밀집을 선택한다.
