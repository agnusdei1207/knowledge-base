## 미리 알고가기

- **대규모 언어 모델 운영(Large Language Model Operations, LLMOps)**: '엘엘엠옵스'로 읽고 프롬프트·검색·모델·평가·배포 운영체계를 표시
- **머신러닝 운영(Machine Learning Operations, MLOps)**: '엠엘옵스'로 읽고 데이터 기반 모델의 학습·배포·재학습 운영체계를 표시
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: '래그'로 읽고 검색 근거를 모델 입력에 결합하는 생성 방식을 표시
- **평가 하네스(Evaluation Harness)**: 평가 자료·기준·실행·결과를 반복 관리하는 시험 장치

## Ⅰ. 개요

- 정의/개념: 프롬프트·RAG·모델·도구·평가·배포를 **버전과 실행 추적으로 연결하는 운영체계**
- **배경/필요성**: 모델 중심 MLOps만으로 찾기 어려운 **비결정적 응답·근거·안전·토큰 비용 회귀 관리**

### 쉽게 이해하기 (학습용)

- 질문·참고 문서·모델·채점표를 한 묶음으로 검증해 승인된 조합만 배포한다.

## Ⅱ. 특징

- **프롬프트·모델·검색 인덱스·도구 버전 결합**으로 실행 구성을 재현한다.
- **질의·검색 근거·응답·도구 호출·비용 추적**으로 실패 원인을 분리한다.
- **자동·사람 회귀 평가와 단계 배포**로 품질·안전·지연·비용을 승격한다.

### 쉽게 이해하기 (학습용)

- 답이 나빠지면 질문·검색 자료·모델의 실행 기록으로 원인을 찾고 사람 평가로 자동 채점의 오판을 바로잡는다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 구성 레지스트리 | 프롬프트·모델·검색 결합본 보관 |
| RAG 파이프라인 | 문서 인덱싱·검색 근거 결합 |
| 평가 하네스 | 데이터·기준·자동·사람 평가 |
| 모델 게이트웨이 | 라우팅·자격·토큰 정책 집행 |
| 추적·피드백 저장소 | 질의·응답·근거·의견 연결 |

> 요약: 구성·게이트웨이·평가·피드백을 연결한다

### 쉽게 이해하기 (학습용)

- 구성 레지스트리·검색·모델·평가·피드백을 연결해 조합별 답과 비용을 확인한다.

## Ⅳ. 원리 및 절차 흐름도

```text
후보 등록 → 회귀 평가 → 전문가 승인 → 단계 배포
                                          ↓
                              운영 판정 ← 실행 추적·피드백
                                ├─ 충족 → 운영 유지
                                └─ 미달 → 롤백 후 수정
```

| 절차 | 설명 |
|:---|:---|
| 후보 등록 | 프롬프트·모델·검색 일괄 등록 |
| 회귀 평가 | 품질·비용·지연을 이전과 비교 |
| 전문가 승인 | 고위험·자동 불일치 검토 |
| 단계 배포 | 승인 구성 반영·미달 시 롤백 |
| 실행 추적·피드백 | 질의·응답·의견을 다음 구성에 반영 |
| 운영 판정 | 품질·안전·지연·비용 승인선 확인 |

> 요약: 구성을 평가·승인·배포하고 피드백으로 갱신한다

### 쉽게 이해하기 (학습용)

- 새 프롬프트·검색 구성을 먼저 검증하고 전문가 승인 뒤 단계 배포하며 사용자 의견을 다음 평가에 반영한다.

## Ⅴ. 종류 및 비교

| AI 모델 운영체계 | LLMOps | MLOps |
|:---|:---|:---|
| 적용 기준 | LLM 품질·안전·비용 통제 | 예측 모델 학습·배포 자동화 |
| 핵심 특징 | 프롬프트·근거·응답 평가 | 데이터·모델 재학습 |
| 한계 | 평가 변동성·근거·비용 누락 | 계보·드리프트 누락 |

> 요약: LLMOps는 응답·근거, MLOps는 재학습을 관리한다

### 쉽게 이해하기 (학습용)

- MLOps는 데이터로 예측 모델을 재학습하고 LLMOps는 프롬프트·검색·모델 조합의 응답을 평가한다.

## Ⅵ. 실무 사례

1. 사내 챗봇의 **검색 근거·답변 일치도**를 평가한다

### 쉽게 이해하기 (학습용)

- 모델·프롬프트·검색 구성을 묶어 근거성·안전성·비용을 회귀 시험한다

## Ⅶ. 결론

- LLM 품질·안전·비용 변화를 통제하기 위해 **모델·프롬프트·RAG 버전·실행 추적·다축 평가**를 검토하고, 전체 구성이 기준을 통과할 때만 승격한다

### 쉽게 이해하기 (학습용)

- 자동 채점과 대화 기록 및 사람 의견을 함께 보고 품질·안전·비용을 통과한 구성만 운영해야 한다.
