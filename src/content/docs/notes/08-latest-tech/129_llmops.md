## 미리 알고가기

- **LLMOps(Large Language Model Operations)**: 프롬프트·검색·모델·평가·배포를 연결하는 운영 체계
- **MLOps(Machine Learning Operations)**: 데이터 기반 예측 모델의 학습·배포·재학습을 연결하는 운영 체계
- **RAG(Retrieval-Augmented Generation)**: 검색한 외부 근거를 모델 입력에 결합하는 생성 방식
- **평가 하네스(Evaluation Harness)**: 평가 자료·기준·실행·결과를 반복 관리하는 시험 장치

## Ⅰ. 개요

- **정의/개념**: LLM 구성·평가·배포·관측을 연결하는 운영 체계다
- **배경/필요성**: 구성 변화의 품질·안전·비용 회귀를 막는다

### 쉽게 이해하기 (학습용)

- 질문·참고 문서·모델·채점표를 한 묶음으로 검증해 승인된 조합만 배포한다.

## Ⅱ. 특징

- 프롬프트·모델·검색 버전 결합은 재현성을 높인다
- 질의·근거·응답 추적은 실패 원인 분석을 돕는다
- 다축 회귀 평가는 품질·안전·비용 악화를 찾는다
- 사람 평가는 자동 채점의 사실성 오판을 줄인다
- 단계적 온라인 평가는 운영 피해와 롤백 시간을 줄인다

### 쉽게 이해하기 (학습용)

- 답이 나빠지면 질문·검색 자료·모델의 실행 기록으로 원인을 찾고 사람 평가로 자동 채점의 오판을 바로잡는다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 구성 레지스트리 | 프롬프트·모델·검색 결합본 보관 |
| RAG 파이프라인 | 문서 인덱싱·검색 근거 결합 |
| 평가 하네스 | 데이터·기준·자동·사람 평가 |
| 모델 게이트웨이 | 라우팅·자격·토큰 정책 집행 |
| 추적·피드백 저장소 | 질의·응답·근거·의견 연결 |

> 요약: 구성·게이트웨이·평가·피드백을 연결한다

### 쉽게 이해하기 (학습용)

- 구성 레지스트리·검색·모델·평가·피드백을 연결해 조합별 답과 비용을 확인한다.

## Ⅳ. 원리 및 절차 흐름도

```text
후보 등록 → 회귀 평가 → 전문가 승인 → 단계 배포
                                          ↓
                              운영 판정 ← 실행 추적·피드백
                                ├─ 충족 → 운영 유지
                                └─ 미달 → 롤백 후 수정
```

| 절차 | 설명 |
|:---|:---|
| 후보 등록 | 프롬프트·모델·검색 일괄 등록 |
| 회귀 평가 | 품질·비용·지연을 이전과 비교 |
| 전문가 승인 | 고위험·자동 불일치 검토 |
| 단계 배포 | 승인 구성 반영·미달 시 롤백 |
| 실행 추적·피드백 | 질의·응답·의견을 다음 구성에 반영 |

> 요약: 구성을 평가·승인·배포하고 피드백으로 갱신한다

### 쉽게 이해하기 (학습용)

- 새 프롬프트·검색 구성을 먼저 검증하고 전문가 승인 뒤 단계 배포하며 사용자 의견을 다음 평가에 반영한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | LLMOps | MLOps |
|:---|:---|:---|
| 핵심 특징 | 생성 응답·검색 구성 평가 | 데이터 기반 모델 재학습 |
| 적용 기준 | LLM 품질·안전·비용 통제 | 예측 모델 학습·배포 자동화 |
| 주요 위험 | 평가 변동성·근거 누락 | 데이터 계보·드리프트 누락 |

> 요약: LLMOps는 응답·근거, MLOps는 재학습을 관리한다

### 쉽게 이해하기 (학습용)

- MLOps는 데이터로 예측 모델을 재학습하고 LLMOps는 프롬프트·검색·모델 조합의 응답을 평가한다.

## Ⅵ. 실무 사례

1. 사내 챗봇의 검색 근거·답변 일치도를 평가한다
2. 상담 서비스의 지연·비용 초과 시 모델을 전환한다

### 쉽게 이해하기 (학습용)

- 사내 챗봇은 검색 설정 변경 때 답과 출처가 함께 맞는지 전문가가 승인한다.
- 상담 서비스는 응답 추적에서 지연·토큰 비용이 넘으면 승인된 대체 모델로 전환한다.

## Ⅶ. 결론

- 구성 버전·추적·사람 평가로 승격·롤백을 결정한다.

### 쉽게 이해하기 (학습용)

- 자동 채점과 대화 기록 및 사람 의견을 함께 보고 품질·안전·비용을 통과한 구성만 운영해야 한다.
