## 미리 알고가기

- **SSDF(에스에스디에프)**: Secure Software Development Framework의 머리글자로, 안전한 개발 관행을 제시하는 프레임워크
- **SLSA(살사)**: Supply-chain Levels for Software Artifacts의 머리글자로, 빌드 출처와 무결성 보증 수준을 정의
- **Provenance(프로비넌스)**: 아티팩트가 어떤 소스·빌더·입력·과정으로 생성됐는지 기록한 출처 증거



## Ⅰ. 개요

- 정의/개념: 소스·의존성·빌드·유통·배포 전 과정의 변조와 오염을 통제하는 보안 체계다
- 기존 한계: 완성된 파일만 검사하면 오염된 의존성·빌드 도구·배포 경로의 변조 원인을 확인하기 어렵다
- 기존 한계: 결과 아티팩트만 검사하면 소스·빌드·의존성·배포 과정의 변조와 승인되지 않은 구성요소 유입을 입증하기 어렵다.
### 쉽게 이해하기 (학습용)

- 승인된 입력과 빌드 증거를 검증해 오염된 아티팩트의 배포를 차단한다.

## Ⅱ. 특징

- 소스·의존성·빌드·유통·배포의 전 경로를 통제한다
- SBOM·Provenance·서명을 아티팩트 다이제스트와 결속한다
- 배포 시 증거를 검증하고 취약점 발견 후 재빌드·교체한다

### 쉽게 이해하기 (학습용)

- 각 개발 단계에서 증거를 만들고 배포 때 검증하며 취약점 발견 시 영향 제품을 재빌드한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[입력 통제: 소스·의존성·정책]
              ↓
[격리 빌드: artifact·SBOM·provenance]
              ↓
       [서명·Registry]
              ↓
     [Admission 검증] → [Runtime]
```

| 설계 요소 | 설명 |
|:---|:---|
| 소스통제 | 권한 최소화·변경 승인·기록 관리 |
| 의존성관리 | 허용 저장소·버전 고정·SBOM 기록 |
| 보안빌드 | 격리 환경·증거 생성·과정 결속 |
| 서명·유통 | 아티팩트 서명 및 증거와 함께 게시 |
| 배포정책 | 배포 시 증거 검증 및 운영 대응 |

> 요약: 개발 증거를 배포 검증·운영 대응까지 연결

### 쉽게 이해하기 (학습용)

- 승인된 소스·의존성으로 빌드하고 생성된 증거를 유통·배포 단계에서 검증한다.

## Ⅳ. 원리 및 절차 흐름도


```text
통제입력
   ↓
격리빌드
   ↓
증거생성
   ↓
배포검증
   ↓
운영대응
```

| 절차 | 설명 |
|:---|:---|
| 1. 통제입력 | 소스 관리와 의존성 버전을 통제함 |
| 2. 격리빌드 | 독립 환경에서 아티팩트와 증거를 생성함 |
| 3. 증거생성 | SBOM·provenance를 다이제스트와 결속함 |
| 4. 배포검증 | 배포 전 서명과 증거 정책을 검사함 |
| 5. 운영대응 | 취약점 확인 후 패치·재출시를 반복함 |

> 요약: 개발 입력을 통제하고 빌드별 증거를 검증해 출시한다

### 쉽게 이해하기 (학습용)

- 아티팩트 다이제스트에 생산 기록·부품표·서명을 묶어 배포와 취약점 대응에 사용한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | SLSA provenance | SBOM | 아티팩트 서명 |
|:---|:---|:---|:---|
| 적용 기준 | 빌드 과정·출처 확인 | 구성요소 영향 분석 | 파일 무결성·서명자 확인 |
| 핵심 특징 | 소스·빌더·입력·산출물 기록 | 구성요소·버전·관계 목록 | 다이제스트와 서명자 신원 결속 |
| 한계 | 구성요소 안전성은 보장하지 않음 | 빌드 과정·파일 무결성 미증명 | 소스·빌드 안전성은 미보장 |

> 요약: SLSA·SBOM·서명을 정책 게이트에서 함께 검증

### 쉽게 이해하기 (학습용)

- Provenance는 생성 과정, SBOM은 구성, 서명은 변조 여부를 설명하므로 함께 검증한다.

## Ⅵ. 실무 사례

1. 컨테이너 배포 정책은 이미지에 결속된 SBOM·Provenance·서명을 확인하고 허용된 빌더와 서명자만 승인한다.

### 쉽게 이해하기 (학습용)

- 빌드 증거와 서명을 배포 시점에 검증하면 변조되거나 출처가 불명확한 이미지를 차단할 수 있다.

## Ⅶ. 결론

- 외부 코드와 빌드 과정의 변조를 방지하기 위해 출처·무결성·빌드 증거를 검토하여 소프트웨어 공급망 보안을 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 소프트웨어 공급망 보안은 개발부터 배포까지 증거 생성과 검증을 연결해야 한다.
