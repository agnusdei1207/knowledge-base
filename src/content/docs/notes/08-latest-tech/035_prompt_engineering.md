## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프롬프트 엔지니어링(Prompt Engineering)**: 모델이 의도한 과업을 수행하도록 지시•문맥•예시•출력 형식을 설계하고 평가로 검증하는 기법을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **출력 계약(Output Contract)**: 모델 응답이 따라야 할 필드•자료형•근거•오류 처리 규칙을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- 정의/개념: 지시•문맥•예시•출력 계약으로 모델 행동을 유도하는 **프롬프트 엔지니어링**
- 배경/필요성: 모호한 입력으로 **정확성•형식•안전성 편차** 발생

#### 한줄 요약

- **지시•문맥•예시•출력 계약**을 평가로 검증

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스템 지시(System Instruction)**: 모델의 역할•행동 범위•우선 규칙을 사용자 입력보다 높은 권한으로 설정하는 지시이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **제로샷(Zero-shot)**: 예시 없이 지시만 제공하여 과업을 수행하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **퓨샷(Few-shot)**: 소수의 입출력 예시로 기대 응답 패턴을 제공하는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **도구 호출(Tool Calling)**: 모델이 검색•계산•외부 기능을 정해진 구조로 요청하도록 연결하는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **프롬프트 주입(Prompt Injection)**: 비신뢰 데이터에 숨은 악성 지시로 상위 지시와 통제를 우회하려는 공격을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

- **시스템 지시**: 행동 범위와 우선 규칙 명시
- **역할•목표•제약**: 성공 조건과 금지 사항 명시
- **제로샷**: 예시 없이 지시만으로 수행
- **퓨샷**: 소수 예시로 기대 응답 패턴 제공
- **도구 호출**: 외부 기능 요청 구조화
- **회귀 평가**: 품질 저하와 프롬프트 주입 검증

#### 한줄 요약

- 고정 평가 세트로 **품질•안전 회귀** 반복 검증

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **성공 조건**: 과업 완료 여부를 관찰•검증할 수 있는 기준이다.
- **역할•목표**: 역할과 과업•성공 조건을 명확히 한 지시 요소이다.
- **지시•제약**: 절차•금지 사항•권한•범위로 행동 경계를 정하는 요소이다.
- **문맥•예시**: 근거와 입출력 사례로 과업 해석을 구체화하는 요소이다.
- **문맥 경계**: 신뢰 지시와 외부 데이터를 구분하는 경계이다.
- **프롬프트 버전**: 지시•예시•출력 계약과 호환 모델의 변경 상태를 재현할 수 있게 식별한 값을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

```text
                         [평가•버전]
              /          /    \          \
       [역할•목표] [지시•제약] [문맥•예시] [출력 계약]
```

선의 의미: 평가•버전은 역할•목표, 지시•제약, 문맥•예시, 출력 계약을 하나의 검증•재현 단위로 묶어 관리하는 정적 프롬프트 구성 계층을 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 역할•목표 | 수행 대상과 **성공 조건** 명시 |
| 지시•제약 | 허용 행동•금지 조건•우선순위 정의 |
| 문맥•예시 | **문맥 경계**와 기대 응답 패턴 제공 |
| 출력 계약 | 필드•자료형•근거•오류 형식 지정 |
| 평가•버전 | 품질•안전 회귀 검증과 이력 관리 |

#### 한줄 요약

- **역할•지시•문맥•출력 계약•평가**의 버전 관리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **회귀 평가(Regression Evaluation)**: 프롬프트나 모델 변경 뒤 기존 과업의 품질 저하 여부를 고정 평가 세트로 확인하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **후보 프롬프트 설계**: 목표•지시•예시•출력 계약을 하나의 시험 버전으로 구성하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **회귀 평가 세트 구성**: 정상•경계•공격 입력과 성공 기준을 고정하는 절차로 정의된다.
- **품질•안전 결함 판정**: 기준 버전과 비교해 품질 회귀와 안전 통제 취약성을 식별하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **수정•버전 승인**: 결함을 보완한 프롬프트 조합과 변경 이력을 확정하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **검증 버전 배포**: 승인된 프롬프트•모델•출력 계약 조합을 운영에 반영하는 절차이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **공격 입력**: 프롬프트 인젝션이나 경계 우회를 시도하여 안전 통제의 실패 여부를 시험하는 입력로 정의된다.

</details>

```text
설계자
  │ 1. 후보 프롬프트 설계
  │ 후보 프롬프트 등록
  ▼
평가기
  │ 2. 회귀 평가 세트 구성
  │ 평가 과업 요청
  ▼
모델
  │ 출력 결과 반환
  ▼
평가기
  │ 3. 품질•안전 결함 판정
  │ 평가 결과 전달
  ▼
설계자
  │ 4. 수정•버전 승인
  │ 5. 검증 버전 배포
  ▼
배포 관리자
```

### 동작 원리

1. 후보 프롬프트 설계: 목표•지시•예시•출력 계약의 단일 버전을 구성함.
2. 회귀 평가 세트 구성: 정상•경계•**공격 입력**과 **성공 조건**을 고정함.
3. 품질•안전 결함 판정: 기준 버전 대비 회귀와 프롬프트 주입 취약성을 식별함.
4. 수정•버전 승인: 결함을 보완한 프롬프트 조합과 변경 이력을 확정함.
5. 검증 버전 배포: 승인된 프롬프트•모델•출력 계약 조합을 배포함.

#### 한줄 요약

- **정상•경계•공격 입력**을 통과한 버전만 배포

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **미세조정(Fine-Tuning)**: 도메인 데이터로 사전학습 모델의 가중치를 추가 갱신하여 반복 행동을 내재화한다.

</details>

| 모델 적응 방식 | 프롬프트 엔지니어링 | 미세조정 |
|:---|:---|:---|
| 적용 기준 | 과업 지시•형식의 빠른 변경 | 반복되는 도메인 행동 내재화 |
| 핵심 특징 | 가중치 없이 입력 시점 행동 유도 | 학습 데이터로 모델 가중치 갱신 |
| 한계 | 입력 토큰 증가•지시 민감성 | 학습 비용•데이터•모델 회귀 |

#### 한줄 요약

- 빠른 지시 변경은 **프롬프트 엔지니어링**, 행동 내재화는 **미세조정**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **업무 규칙 검증**: 출력 구조가 유효한지와 별개로 값의 의미와 업무 제약을 충족하는지 확인하는 절차이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **도구 권한 제한**: 모델이 요청할 수 있는 자원•행동•인자를 최소 범위로 제한하여 오판의 피해를 줄이는 통제을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 지시 모호성 | **성공 조건**•금지 조건•출력 예시 명시 | 응답 편차 감소 |
| 정형 출력 의미 오류 | **출력 계약**과 **업무 규칙 검증** 분리 | 구조•내용 오류 동시 탐지 |
| 프롬프트 주입 | **문맥 경계**와 **도구 권한 제한** | 악성 입력 행동 전이 억제 |
| 모델 변경 회귀 | **회귀 평가** | 배포 전 품질 저하 탐지 |

#### 한줄 요약

- **구조•업무 의미•안전**을 분리하여 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **모델 적응 방식 선택 기준**: 변경이 잦은 과업에는 프롬프트 엔지니어링을, 반복 행동 내재화에는 미세조정을 적용하는 기준이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 변경이 잦은 과업은 **프롬프트 엔지니어링**, 반복 행동 내재화는 **미세조정** 선택

#### 한줄 요약

- **변경 빈도•행동 반복성**에 따라 모델 적응 방식 결정
