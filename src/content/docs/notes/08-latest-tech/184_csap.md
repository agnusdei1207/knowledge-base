## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **클라우드서비스 보안인증(Cloud Security Assurance Program, CSAP)**: 클라우드서비스가 정한 보안인증기준에 적합한지 평가•인증하고 유지 상태를 관리하는 제도로 정의된다.
- **인증 범위**: 인증 효력이 적용되는 서비스•자산•조직•물리 위치•운영 절차의 경계로 정의된다.

</details>

- 정의: 클라우드서비스의 보안인증기준 적합성을 평가•관리하는 **CSAP** 제도
- 배경/필요성: 공공기관이 민간 클라우드 서비스(IaaS, PaaS, SaaS)를 도입할 때 개별 기관마다 보안성을 자체 평가할 경우 천문학적인 중복 심사 비용이 발생하고, 보안성이 검증되지 않은 클라우드 도입 시 국가 중요 공공 정보 유출 및 사이버 테러 위험에 노출되는 한계에 직면함에 따라, 과학기술정보통신부와 KISA가 클라우드 서비스의 안전성과 신뢰성을 국가 차원에서 객관적으로 검증하고 등급별 보안기준을 차등 적용하는 CSAP(Cloud Security Assurance Program / 클라우드 보안인증제 / 상•중•하 3등급 체계, KISA 주관, IaaS/PaaS/SaaS/DaaS 인증 기준, 물리적 망분리 vs 논리적 망분리, 취약점 점검 & 모의해킹) 제도를 도입하여 **국가 공공기관에 도입되는 민간 클라우드의 정보보호 관리체계 및 기술적 안정성을 사전에 공인 검증, 시스템 중요도에 따른 상•중•하 등급제 운영을 통해 공공 데이터 보안성 확보와 민간 클라우드 혁신의 조화 달성, 사업자의 인증 획득 및 정기 사후관리를 통한 클라우드 공급망 보안 신뢰성 확보**를 달성할 필요

#### 한줄 요약

- CSAP는 기관별 개별 점검을 **공통 평가** 한 번으로 대체해 도입 비용을 줄이는 대신, 인증 범위 밖 구성과 인증 후 변경분은 여전히 이용 기관이 확인해야 할 몫으로 남긴다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **증적 기반 평가**: 문서•현장•기술 기록으로 보호조치의 설계와 실제 운영 적합성을 확인하는 방식이다.
- **변경관리**: 인증받은 서비스와 기반 환경의 변경 영향 및 재평가 필요성을 통제하는 활동을 의미한다.

</details>

- 서비스•자산•조직•조건에만 효력이 있는 **범위 한정 인증**
- 서면•현장•기술 기록 기반 **증적 기반 평가**
- 최초 인증 이후 유효성을 확인하는 **사후•변경 관리**

#### 한줄 요약

- 서비스 범위 명시와 변경 후 **인증기준 충족 여부** 확인

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **평가기관**: 서면•현장•기술 평가를 수행하고 부적합 보완 결과를 확인하는 기관을 의미한다.
- **보안인증기준**: 서비스 유형•등급별로 충족해야 할 관리적•기술적 보호조치를 정한 기준이다.
- **인증신청인•범위**: 인증을 신청한 클라우드 서비스 제공자와 심사에 포함할 서비스•시스템•운영 경계이다.
- **인증•사후관리**: 평가 결과에 따라 인증을 부여하고 유효기간 동안 변경•취약점•준수 상태를 확인하는 절차이다.

</details>

```text
                  [인증신청인]
                        |
                   [인증 범위]
                        |
                 [보안인증기준]
                        |
                    [평가기관]
                        |
                [인증•사후관리]
```

| 구성요소 | 책임 |
|:---|:---|
| 인증신청인 | 서비스 범위 정의와 **보호조치•평가 증적** 제출 |
| 인증 범위 | 서비스•자산•조직•위치의 **적용 경계** 명시 |
| 보안인증기준 | 서비스 유형•등급별 **보안인증기준** 제공 |
| 평가기관 | 서면•현장•기술 평가와 **부적합 보완** 확인 |
| 인증•사후관리 | 인증서 발급과 유지•변경 및 **갱신 상태** 관리 |

#### 한줄 요약

- 사업자 **인증 범위•증적**과 평가기관 검증 기반 상태 관리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **서비스형 인프라(Infrastructure as a Service, IaaS)**: 서버•저장장치•네트워크 등 기반 자원을 제공하는 서비스 유형을 말한다.
- **서비스형 소프트웨어(Software as a Service, SaaS)**: 제공자가 운영하는 응용 소프트웨어를 제공하는 서비스 유형을 말한다.
- **서비스형 데스크톱(Desktop as a Service, DaaS)**: 가상 데스크톱 환경을 원격으로 제공하는 서비스 유형이다.
- **인증위원회**: 평가 결과를 심의해 인증•보완 여부를 판단하는 조직이다.

</details>

```text
[신청 사업자] ── 인증 범위 문의 ──▶ [인증 체계]
[신청 사업자] ◀─ 적용 유형•기준 안내 ─ [인증 체계]
      │ 1. 신청서•증적
      ▼
 [평가기관]
      │ 2. 평가•보완 결과
      ▼
 [인증 심의]
      │ 3. 인증 결정
      ▼
 [사후관리] ── 인증 상태•사후평가 일정 ──▶ [신청 사업자]
```

### 동작 원리

1. 신청서•증적: 인증 범위와 **보호조치 구현 증거** 제출
2. 평가•보완 결과: 기준 충족 여부와 **부적합 시정 결과** 제공
3. 인증 결정: **인증위원회** 심의에 따른 인증•보완 결정

#### 한줄 요약

- **신청•평가•인증 결정•사후관리**의 판정 연계

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **최초평가**: 신규 또는 중대 변경 서비스의 인증 범위와 기준 적합성을 종합 검증하는 평가이다.
- **사후평가**: 인증 이후 보호조치와 주요 변경이 계속 유효한지 확인하는 평가이다.
- **갱신평가**: 유효기간 연장 전에 인증기준 적합성을 다시 검증하는 평가이다.

</details>

| 구분 | 최초평가 | 사후평가 | 갱신평가 |
|:---|:---|:---|:---|
| 적용 기준 | 신규•중대 변경 **인증 서비스** | 유효기간 중 **인증 서비스** | 유효기간 연장 **대상 서비스** |
| 핵심 특징 | 범위와 기준 적합성의 **종합 검증** | 보호조치 유지와 **주요 변경** 확인 | 기준 적합성의 **재검증**•**갱신** |
| 주요 한계 | **준비 기간•증적 구축** 부담 | 범위 밖 변경의 **별도 통제** | 미갱신 시 **인증 효력 상실** |

#### 한줄 요약

- **신규•유지•유효기간 연장**은 인증을 처음 얻을 때와 지킬 때의 검증 깊이를 다르게 매긴 것이며, 인증 후 변경 폭이 클수록 유지 평가가 사실상 신규 평가에 가까워진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **구성 기준선**: 인증 시점에 승인된 서비스•자산•리전•하도급•운영 절차의 상태를 기록한 기준을 말한다.
- **잔여 위험**: 인증 보호조치를 적용한 뒤에도 기관의 업무 특성 때문에 남아 별도 통제가 필요한 위험을 의미한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **실사용 범위 불일치**에 따른 미인증 기능 사용 | **서비스•자산•위치•유효 상태**를 실제 구성과 대조 | 인증 범위•**실제 구성 일치성** 확보 |
| **변경 누락**에 따른 아키텍처•하도급 통제 무효화 | **영향 분석•구성 기준선•재평가** 확인 | **인증 통제 유효성** 유지 |
| **인증 과신**에 따른 업무별 추가 요구 누락 | **업무 위험평가•계약•운영 통제** 추가 | 업무 **잔여 위험** 감소 |

#### 한줄 요약

- **범위•변경•잔여 위험**별 인증 통제 효과 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실제 구성 일치성**: 사용 중인 리전•기능•외부 서비스•운영 절차가 인증 범위와 같은 상태이다.
- **재평가**: 중대한 변경 뒤 기존 인증 통제가 계속 유효한지 다시 확인하는 절차이다.

</details>

- 국내 공공 부문 클라우드 전환 및 SaaS 생태계 확산의 법적•보안적 관문 역할을 수행하는 **공공 클라우드 서비스 보안성 검증 및 신뢰성 평가의 최고 국가 표준(Cloud Security Assurance Program: CSAP / 3-Tier Classification: High-Medium-Low / IaaS, PaaS, SaaS, DaaS Certification / Physical & Logical Network Separation / Post-audit Lifecycle Governance)의 확고한 표준**으로 확고히 자리 잡았으며, 다층보안체계(MLS) 및 글로벌 CSP의 공공 진출 표준과 연계 개편되는 가운데, 실무 공공 클라우드 사업 수주 및 솔루션 도입 시에는 **자사 서비스의 공공 데이터 민감도를 분석하여 최적 등급(상/중/하) 인증을 선제 취득하고, 인증 범위와 실제 프로덕션 인프라 구성 간의 100% 일치성 유지 및 연례 사후평가(Surveillance Audit) 체계**를 결합하여 완벽한 컴플라이언스 준수와 공공 비즈니스 영속성을 완성

#### 한줄 요약

- 인증서는 서비스 전체가 아니라 명시된 범위에 대한 보증이므로, 도입 기관이 **인증 범위•실제 구성 일치성**을 스스로 확인하지 않으면 인증이 오히려 검증했다는 착각을 만든다.
