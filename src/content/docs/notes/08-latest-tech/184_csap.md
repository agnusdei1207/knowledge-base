## 미리 알고가기

- **CSAP(씨에스에이피)**: Cloud Security Assurance Program의 머리글자로, 클라우드서비스의 보안인증기준 적합성을 검증
- **KISA(키사)**: 한국인터넷진흥원으로, 인증위원회 운영과 인증서 발급·사후관리를 담당
- **인증 범위**: 인증서에 명시된 서비스·등급·자산·운영 조직에만 인증 효력이 적용



## Ⅰ. 개요

- 정의/개념: 클라우드서비스가 법령에 따른 보안인증기준에 적합한지 평가·인증하는 제도다
- 기존 한계: 기관별 자체 점검만으로는 클라우드 제공자의 보호조치 수준을 일관되게 검증하기 어렵다
- **배경/필요성**: 공공기관이 검증된 보안 수준과 인증 범위를 근거로 서비스를 선택하기 위함이다

### 쉽게 이해하기 (학습용)

- 서비스와 운영 범위의 보호조치를 확인하는 공공 검사표임

## Ⅱ. 특징

- 서비스 유형·등급·인증 범위를 기준으로 보호조치를 평가한다
- 서면·현장·취약점 점검과 보완조치로 기준 적합성을 확인한다
- 최초·사후·갱신 평가로 인증의 유효 상태를 관리한다

### 쉽게 이해하기 (학습용)

- 현재는 하등급 중심이나 인증 후 별도 안전 검토가 필수임

## Ⅲ. 아키텍처 및 구성요소

```text
[신청 사업자] → [평가기관] → [KISA·인증위원회]
      ↑               │               ↓
      └──── 보완조치 ─┘        [인증·사후관리]
```

| 설계 요소 | 설명 |
|:---|:---|
| 인증신청인 | 서비스·자산 범위 지정과 증적 제출 |
| 평가기관 | 서면·현장·취약점 평가와 보완 확인 |
| KISA | 평가 요청·인증위원회 운영·사후관리 |
| 인증위원회 | 평가 결과를 심의해 인증 여부 결정 |
| 보안인증기준 | 관리·물리·기술 보호조치의 판단 기준 |

> 요약: 평가기관이 검증하고 KISA 위원회가 인증을 결정한다

### 쉽게 이해하기 (학습용)

- 사업자가 범위와 증거를 내면 평가기관이 확인하고 인증위원회가 최종 결정한다.
## Ⅳ. 원리 및 절차 흐름도

```text
확인
  ↓
신청
  ↓
평가
  ↓
보완
  ↓
인증/유지
```

| 절차 | 설명 |
|:---|:---|
| 범위 확인 | 서비스 유형·등급·인증 자산을 확정 |
| 신청 | 신청서·명세서·보호조치 증적 제출 |
| 평가 | 서면·현장·취약점 점검 수행 |
| 보완·심의 | 부적합 보완 후 위원회에서 심의 |
| 유지 | 사후·변경·갱신 평가로 상태 관리 |

> 요약: 유형 확인 후 평가·보완·심의를 거쳐 인증 상태를 유지한다

### 쉽게 이해하기 (학습용)

- 등급과 범위를 정하고 현장·기술 점검의 미흡 사항을 보완한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 최초 평가 | 사후 평가 | 갱신 평가 |
|:---|:---|:---|:---|
| 적용 기준 | 신규 인증 신청 | 인증 유효기간 중 | 유효기간 만료 전 |
| 핵심 특징 | 전체 기준 적합성 심사 | 운영 상태·변경 사항 확인 | 전체 기준 재평가 후 연장 |
| 한계 | 평가 준비 비용과 기간 필요 | 인증 범위 밖 변경은 별도 관리 | 미갱신 시 인증 효력 종료 |

> 요약: 최초 인증 후 사후평가를 거쳐 만료 전에 갱신한다

### 쉽게 이해하기 (학습용)

- 처음 영업 검사를 받고, 유효기간 동안 해마다 유지 상태를 확인하며, 5년이 끝나기 전에 다시 검사받아 기간을 연장하는 구조임

## Ⅵ. 실무 사례

1. 공공기관은 SaaS 도입 전 인증서의 서비스명·리전·유효기간을 실제 이용 구성과 대조한다.

### 쉽게 이해하기 (학습용)

- 인증 마크만 보지 않고 도입할 서비스가 인증 범위와 유효기간 안에 있는지 확인한다.

## Ⅶ. 결론

- 공공 클라우드의 보안 적합성을 확보하기 위해 인증 범위·유효 상태·기관별 요구사항을 검토하여 CSAP 적용 여부를 판단해야 한다.

### 쉽게 이해하기 (학습용)

- CSAP 인증서와 실제 이용 구성이 일치해야 공공기관 서비스에 적합하다.
