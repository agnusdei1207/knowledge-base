## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **토큰화(Tokenization)**: 원문 문자열을 모델 어휘에 정의된 토큰 조각으로 나누고 정수 ID 열로 변환하는 과정이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **토큰 식별자(Token Identifier, Token ID)**: 모델 어휘의 각 토큰에 대응하여 신경망 입력으로 사용하는 정수 식별자로 정의된다.

</details>

- 정의/개념: 입력 문자열을 모델 어휘의 부분 단위로 분할하고 각 단위를 Token ID로 변환하는 **토큰화**임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 배경/필요성: 신경망은 원문 문자열이 아니라 **토큰 식별자**를 입력으로 요구하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- 문자열을 어휘 조각과 **Token ID**로 변환한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **어휘(Vocabulary)**: 모델이 직접 표현하고 생성할 수 있는 토큰과 ID의 정의 집합을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **서브워드(Subword)**: 단어보다 작지만 반복되는 형태나 의미를 보존하는 가변 길이 문자열 조각을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **미등록어(Out-of-Vocabulary, OOV)**: 어휘에 완전한 형태로 존재하지 않아 더 작은 조각으로 분절해야 하는 문자열로 정의된다.

</details>

- 정규화•사전 분절•학습 규칙으로 분절 경계를 결정하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- 희귀어를 문자보다 큰 조각으로 표현하는 **미등록어 완화**가 핵심임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- **어휘**가 커지면 토큰 수는 줄지만 임베딩 매개변수는 증가하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- 어휘 크기와 토큰 수 사이의 비용을 절충한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **유니코드 정규화(Unicode Normalization)**: 같은 문자를 나타내는 여러 코드 조합을 일관된 문자열 형태로 맞추는 처리을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **바이트 페어 인코딩(Byte Pair Encoding, BPE)**: 말뭉치에서 자주 함께 나타나는 문자•토큰 쌍을 반복 병합하여 서브워드 어휘를 만드는 알고리즘을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **스페셜 토큰(Special Token)**: 시퀀스 시작•종료•패딩•역할 구분처럼 모델 제어에 사용하는 특수 ID을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

```text
[정규화기]──[사전 분절기]──[서브워드 모델]
                                │
                         [식별자 매퍼]──[복호기•디코딩]
```

선의 의미: 표기•경계•조각•ID•문자열 복원 책임의 정적 연결을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 정규화기 | **유니코드 정규화**와 공백 표기 정책 적용 |
| 사전 분절기 | 공백•구두점으로 초기 문자열 경계 생성 |
| 서브워드 모델 | **BPE•어휘 조각 탐색** |
| 식별자 매퍼 | 조각•**스페셜 토큰**을 Token ID에 대응 |
| 복호기•디코딩 | Token ID에서 출력 문자열 복원 |

#### 한줄 요약
- **정규화•분절•서브워드•ID 매핑•복호**를 구성한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **사전 분절(Pre-tokenization)**: 공백•구두점•언어 규칙으로 서브워드 탐색 전에 기본 문자열 경계를 만드는 과정을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **식별자 매핑(Identifier Mapping, ID Mapping)**: 분절한 문자열 조각과 제어 기호를 어휘표의 정수 식별자에 대응시키는 과정로 정의된다.
- **유니코드•공백 정규화**: 학습과 운영에 동일한 문자•공백 표기 정책을 적용하는 절차을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **초기 문자열 경계 분절**: 공백•구두점•언어 규칙으로 서브워드 탐색 전 경계를 만드는 절차을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **BPE 서브워드 분절**: BPE 어휘에서 입력을 구성할 문자열 조각을 탐색하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **토큰•특수 ID 대응**: 일반 조각과 제어 기호를 어휘표의 정수 식별자에 매핑하는 절차을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

```text
원문 문자열
     │
     ▼
정규화기
     │ 1. 유니코드•공백 정규화
     │ 정규화 문자열 전달
     ▼
분절기
     │ 2. 초기 문자열 경계 분절
     │ 3. BPE 서브워드 분절
     │ 서브워드 조각 전달
     ▼
어휘 매퍼
     │ 4. 토큰•특수 ID 대응
     │ 토큰 ID 시퀀스
     ▼
출력
```

1. **유니코드•공백 정규화**: 학습•운영에 동일한 표기 정책을 적용함.
2. **초기 문자열 경계 분절**: **사전 분절**로 기본 경계를 생성함.
3. **BPE 서브워드 분절**: 어휘에 존재하는 최장•최적 조각을 탐색함.
4. **토큰•특수 ID 대응**: **식별자 매핑**으로 정수 ID에 대응함.

#### 한줄 요약
- 학습•운영 분절 규칙을 일치시켜 ID 의미를 보존한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **단어 단위 토큰화**: 단어 전체를 하나의 Token ID로 표현하여 토큰열은 짧지만 어휘와 미등록어가 늘어나는 방식로 정의된다.
- **서브워드 단위 토큰화**: 빈번한 문자열 조각을 가변 길이로 사용하여 어휘 크기와 토큰 수를 절충하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **문자•바이트 단위 토큰화**: 모든 입력을 기본 문자나 바이트로 분해하여 미등록어를 없애지만 토큰열이 길어지는 방식로 정의된다.

</details>

- **단어 단위 토큰화**, **서브워드 단위 토큰화**, **문자•바이트 단위 토큰화**를 어휘 크기와 미등록어 기준으로 구분하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

| 비교 기준 | 단어 단위 | 서브워드 단위 | 문자•바이트 단위 |
|:---|:---|:---|:---|
| 적용 기준 | 제한 어휘•명확한 단어 경계 | 범용•다국어 모델 | 미지 문자열•어휘 최소화 |
| 핵심 특징 | 단어별 직접 ID 대응 | 빈번 문자열의 가변 길이 조각화 | 모든 입력의 기본 단위 분해 |
| 한계 | 큰 어휘•**미등록어** 발생 | 말뭉치 편향•분절 품질 의존 | 토큰열 증가•문맥 비용 확대 |

#### 한줄 요약
- 범용은 **서브워드 단위 토큰화**, 미지 문자열은 **문자•바이트 단위 토큰화**가 적합하다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **토크나이저 버전 고정**: 학습과 운영에서 같은 정규화•어휘•ID 규칙을 사용하도록 파일과 버전을 명시하는 통제을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **복원율**: 토큰 ID를 다시 문자열로 복호했을 때 원문의 정보와 표기가 보존되는 정도을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **특수 토큰 주입**: 사용자 문자열이 제어 토큰으로 해석되어 프롬프트 역할이나 경계를 바꾸는 공격이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 학습•운영의 정규화 정책 불일치 | **토크나이저 버전 고정** | 입력 ID 재현성 확보 |
| 모델 임베딩과 어휘 ID 불일치 | 어휘 해시•**스페셜 토큰** ID 검증 | 잘못된 토큰 해석 방지 |
| 한국어•전문용어의 과도한 분절 | 도메인별 토큰 수•**복원율** 평가 | 문맥 길이•표현 효율 개선 |
| 사용자 입력의 **특수 토큰 주입** | 제어 토큰 이스케이프•허용 목록 | 프롬프트 경계 보호 |

#### 한줄 요약
- **토큰 수•복원율•ID 일치**로 품질•비용을 통제한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **복호(Decoding)**: 생성된 Token ID 열을 사람이 읽을 수 있는 문자열로 되돌리는 처리을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

- 범용•다국어에는 **서브워드 단위 토큰화**, 미지 문자열에는 **문자•바이트 단위 토큰화**를 선택하고 **복호**로 문자열을 복원하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- 언어와 미지 문자열 비중에 따라 분절 단위를 선택한다. 체계 적용
