## 미리 알고가기

- **LLM10 무제한 소비**: 통제되지 않은 모델·도구 사용이 자원·비용·서비스 용량을 소진하는 위험
- **토큰(Token)**: 모델이 입력과 출력을 처리하고 사용량을 계량하는 문자열 단위
- **예산 원장(Budget Ledger)**: 사용자별 토큰·시간·도구·비용의 한도와 소비를 기록하는 장부

## Ⅰ. 개요

- **정의/개념**: 무제한 추론이 자원·비용을 소진하는 위험이다
- **배경/필요성**: 요청별 작업량 차이의 가용성·과금 피해를 막는다

### 쉽게 이해하기 (학습용)

- 식당의 손님 수뿐 아니라 주문량과 조리 시간을 함께 제한해야 주방 독점을 막을 수 있다.

## Ⅱ. 특징

- 2025판은 자원·비용·모델 복제 위험을 함께 다룬다
- 같은 한 건도 토큰·시간에 따라 소비량이 달라진다
- 비용 비대칭은 적은 요청으로 큰 자원을 고갈시킨다
- 에이전트 반복은 외부 서비스 비용까지 누적한다
- 다차원 예산은 요청 수 제한의 사각지대를 줄인다

### 쉽게 이해하기 (학습용)

- 짧은 질문과 긴 문서 분석·도구 반복은 같은 한 건이어도 서버 시간과 비용이 크게 다르다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 자원 게이트웨이 | 주체·모델·입출력 한도 식별 |
| 예산 원장 | 토큰·시간·도구·비용 기록 |
| 입장 제어기 | 예산·용량으로 실행 여부 결정 |
| 실행 감시기 | 사용량 계량과 초과 중단 |
| 격리 실행 풀 | 주체별 큐·동시성·용량 분리 |

> 요약: 예산 원장과 실행 감시기가 소비 상한을 집행한다

### 쉽게 이해하기 (학습용)

- 실행 전에 예산과 자리를 예약하고 실행 중 사용량이 한도를 넘으면 멈춰 다른 사용자의 자원을 보호한다.

## Ⅳ. 원리 및 절차 흐름도

```text
요청 식별 → 소비 산정 → 예산 예약
                        ├─ 실패 → 거절
                        └─ 성공 → 풀 입장
                                    ↓
                        실시간 계량 → 상한 초과시 중단
                                    ↓
                        실제 소비 정산
```

| 절차 | 설명 |
|:---|:---|
| 소비 산정 | 입출력·시간·도구 비용 계산 |
| 예산 예약 | 사용자별 최대 소비량 확보 |
| 풀 입장 | 예약 성공 요청만 큐에 배치 |
| 실시간 계량 | 토큰·시간·도구 누적과 중단 |
| 소비 정산 | 실제 소비 확정·잔여 예산 반환 |

> 요약: 최대 소비를 예약하고 실시간 계량으로 중단한다

### 쉽게 이해하기 (학습용)

- 최대 소비량을 먼저 예약하고 실제 사용량을 재며 초과 시 중단한 뒤 남은 예산을 반환한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 요청 건수 한도 | 토큰·시간 예산 | 도구 호출·단계 예산 |
|:---|:---|:---|:---|
| 핵심 특징 | 사용자별 요청 횟수 | 입출력 토큰·실행 시간 | 도구 호출·반복·외부 비용 |
| 적용 기준 | 호출 폭주 통제 | 추론 비용 편차 통제 | 에이전트 반복 통제 |
| 주요 위험 | 고비용 요청 누락 | 외부 작업 누락 | 호출별 추론 비용 누락 |

> 요약: 건수·추론·도구 소비에 서로 다른 예산을 적용한다

### 쉽게 이해하기 (학습용)

- 요청 수와 토큰·시간 및 도구 호출은 서로 다른 비용이므로 하나의 제한만으로 과소비를 잡을 수 없다.

## Ⅵ. 실무 사례

1. 추론 서비스는 고객별 토큰·시간 예산을 예약한다
2. 코드 에이전트는 토큰·시간·도구 한도를 계량한다

### 쉽게 이해하기 (학습용)

- 여러 고객이 쓰는 서비스는 고객별 큐를 나누고 토큰·시간 예산을 넘는 요청을 대기시킨다.
- 코드 에이전트는 생성량·시간·도구 호출 중 하나라도 한도에 닿으면 작업을 멈춘다.

## Ⅶ. 결론

- 주체별 토큰·시간·도구 호출을 예산으로 관리한다.

### 쉽게 이해하기 (학습용)

- 요청 수뿐 아니라 토큰·시간·도구 호출을 제한하고 실행 풀도 나눠야 한 사용자의 독점을 막을 수 있다.
