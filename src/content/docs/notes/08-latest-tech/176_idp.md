## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **내부 개발자 플랫폼(Internal Developer Platform, IDP)**: 공통 인프라•배포•운영 기능을 개발자가 직접 소비하는 셀프서비스 제품이다.
- **플랫폼 엔지니어링**: 개발자가 인프라 복잡성을 직접 다루지 않도록 재사용 가능한 내부 제품을 설계•운영하는 활동이다.

</details>

- 정의: 공통 개발•운영 기능을 골든 패스로 제공하는 **IDP**
- 배경/필요성: 수십 개의 개발팀이 개별적으로 클라우드 인프라(AWS/GCP/Azure), 쿠버네티스 매니페스트, CI/CD 스크립트, 모니터링 및 보안 가드레일을 중복 구축함에 따라 조직 전체의 도구 파편화와 극심한 인지 부하(Cognitive Load)가 발생하고, 인프라 변경 시마다 티켓 기반 수동 승인 병목으로 인해 릴리즈 리드타임이 지연되는 한계에 직면함에 따라, 개발자가 단일 셀프서비스 포털을 통해 승인된 템플릿과 표준화된 개발/배포 경로(Golden Path)를 즉시 소비할 수 있도록 지원하는 내부 개발자 플랫폼인 IDP(Internal Developer Platform / Backstage, Port, Humanitec, Golden Path / Golden Road, Self-service API & CLI, Score Spec, Service Catalog, TechDocs, RBAC & Policy-as-Code: OPA) 아키텍처를 도입하여 **개발자 셀프서비스를 통한 환경 프로비저닝 시간(수 주 $\rightarrow$ 수 분)의 극적 단축 및 Time-to-Market 극대화, 전사 소프트웨어 자산/서비스 카탈로그(Service Catalog)의 중앙 집중식 가시화 및 메타데이터 통합, 보안•컴플라이언스 가드레일(Policy-as-Code)이 자동 내장된 골든 패스 제공을 통한 개발자 인지 부하 해소**를 달성할 필요

#### 한줄 요약

- 검증된 메뉴에서 선택하면 저장소와 배포 환경 및 운영 기준이 함께 준비되는 내부 서비스다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **골든 패스(Golden Path)**: 조직의 보안•운영 기준을 안전한 기본값으로 내장한 권장 개발•배포 경로이다.
- **확장 지점**: 표준 경로로 처리하지 못한 요구를 관리된 방식으로 연결•변경하도록 제공하는 인터페이스이다.
- **명령줄 인터페이스(Command-Line Interface, CLI)**: 문자 명령으로 플랫폼 기능을 호출하는 사용자 접점이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능과 데이터를 호출하기 위한 명세화된 접점이다.

</details>

- 포털•**CLI**가 공유하는 **플랫폼 API 계약**
- 표준 템플릿과 기본 정책을 묶은 **골든 패스**
- 강제 경로가 아닌 **셀프서비스•확장 지점**
- 팀별 정책 편차를 줄이는 **정책 엔진**

#### 한줄 요약

- 표준 경로는 쉽게 쓰게 만들고 예외가 필요한 팀에는 관리된 확장 방법을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **개발자 인터페이스**: 포털•CLI•선언 파일을 통해 기능을 요청하고 상태를 확인하는 접점이다.
- **플랫폼 API**: 개발자 인터페이스가 공통으로 사용하는 기능 계약과 자원 상태의 진입점이다.
- **정책 엔진**: 셀프서비스 요청이 보안•운영 가드레일을 만족하는지 자동 검증하는 구성요소이다.
- **개발자 포털**: 서비스 카탈로그와 표준 작업 흐름을 한곳에서 탐색•요청하는 셀프서비스 인터페이스이다.
- **서비스 카탈로그**: 조직이 승인한 서비스 유형과 골든 패스를 탐색하는 목록이다.
- **템플릿**: 승인된 개발•배포 경로와 자원 구성을 재사용 가능한 형태로 제공하는 개념이다.
- **자동화 계층**: 요청을 지속적 통합•배포와 코드형 인프라 작업으로 변환해 기반 도구에서 실행하는 구성요소이다.
- **지속적 통합•지속적 전달(Continuous Integration and Continuous Delivery, CI/CD)**: 코드 변경을 자동 검증하고 배포 가능 상태로 전달하는 방식을 말한다.
- **코드형 인프라(Infrastructure as Code, IaC)**: 인프라 구성을 코드로 선언•버전 관리•자동 적용하는 방식을 의미한다.
- **기반 도구**: 클라우드•클러스터•저장소•배포 시스템의 실제 작업을 수행하는 개념이다.
- **관측 계층**: 플랫폼 요청의 처리 상태•리드 타임•실패•사용량을 수집하는 구성요소이다.

</details>

포털•CLI의 공통 **플랫폼 API**와 CI/CD•IaC 자동화 구조

```text
                  [개발자 인터페이스]
                           |
                      [플랫폼 API]
                      /           \
           [서비스 카탈로그]     [정책 엔진]
                  |                  |
              [템플릿] ----- [자동화 계층]
                                     |
                                [기반 도구]
                                     |
                                [관측 계층]
```

선의 의미: 공통 진입점•정책 검증•자동 실행•상태 수집 관계

| 구성요소 | 책임 |
|:---|:---|
| 개발자 인터페이스 | 포털•CLI•선언 파일의 **요청•상태 제공** |
| 플랫폼 API | 기능 계약과 자원 상태의 **공통 진입점** |
| 서비스 카탈로그 | 승인된 서비스•**골든 패스 탐색** |
| 템플릿 | 재사용 가능한 **자원 구성** 제공 |
| 자동화 계층 | **CI/CD•IaC 작업** 실행 |
| 정책 엔진 | **보안•운영 가드레일** 검증 |
| 기반 도구 | **클라우드•클러스터 작업** 수행 |
| 관측 계층 | **처리 상태•사용 지표** 수집 |

#### 한줄 요약

- 포털과 CLI는 진입점만 다를 뿐 같은 API를 지나므로 **정책 검증•자동 실행**이 한 곳에 모이며, 그 덕분에 진입 경로가 늘어도 지켜야 할 규칙은 한 벌로 유지된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **카탈로그**: 개발자가 승인된 서비스 유형•템플릿•골든 패스를 탐색하는 목록을 말한다.
- **채택률**: 대상 개발팀이나 서비스 가운데 플랫폼 기능을 실제 사용한 비율이다.

</details>

```text
[개발자 인터페이스] ── 기능 사양 요청 ──▶ [플랫폼 API]
                                              │ 1. 골든 패스 선택
                                              ▼
                                     [카탈로그•템플릿]
                                              │ 2. 템플릿•정책 실행
                                              ▼
                                     [자동화•정책 엔진]
                                              │ 3. 자원 생성•배포
                                              ▼
                                      [기반 도구•관측]
                                              │ 4. 상태•사용 지표 환류
                                              ▼
[개발자 인터페이스] ◀─ 실행 상태•결과 반환 ─ [플랫폼 API]
```

### 동작 원리

1. 골든 패스 선택: 지원 범위와 승인 템플릿 결정
2. 템플릿•정책 실행: 기본값 결합과 보안•운영 규칙 검증
3. 자원 생성•배포: 저장소•파이프라인•실행 환경 자동 구성
4. 상태•사용 지표 환류: 리드 타임•실패•채택률 반영

#### 한줄 요약

- 골든 패스 자동 실행과 **리드 타임•실패 원인 환류**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **개발자 포털**: 플랫폼 기능•카탈로그•문서의 탐색과 요청 진입점을 제공하는 사용자 인터페이스이다.
- **플랫폼 팀**: 내부 개발자 플랫폼의 로드맵•지원•운영•성과를 제품 관점으로 소유하는 조직이다.
- **사용자 인터페이스(User Interface, UI)**: 사용자가 플랫폼 기능을 탐색하고 조작하는 접점이다.

</details>

| 플랫폼 개념 | IDP | 개발자 포털 | 플랫폼 팀 |
|:---|:---|:---|:---|
| 적용 기준 | **셀프서비스 전체 제품** | **탐색•요청 진입점** | **제품 소유•운영 조직** |
| 핵심 특징 | **API•템플릿•자동화•정책** 통합 | **UI•카탈로그•문서** 제공 | **로드맵•지원•성과** 관리 |
| 한계 | **통합•추상화•운영 복잡성** | 포털만으로 **실행 자동화 불가** | **공급자 중심화** |

#### 한줄 요약

- 포털은 IDP의 화면 한 층일 뿐이라 포털만 세우면 인지부하가 화면 뒤로 옮겨질 뿐이며, **제품 소유**와 자동화 실행까지 갖출 때 비로소 중복 자동화가 줄어든다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **셀프서비스**: 개발자가 수동 요청이나 대기 없이 API•포털•CLI로 필요한 기능을 직접 사용하는 방식이다.
- **탈출 경로**: 추상화 아래의 실행 상태와 원본 도구에 접근해 예외 처리•진단을 수행하는 경로이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 일정 기간에 달성하기로 정한 사용자 중심 서비스 품질 목표이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사용하지 않는 **골든 패스** | 개발자 조사•파일럿•**채택률 측정** | **인지 부하** 감소 |
| 과도한 **추상화**로 디버깅 가시성 저하 | 상태•실행 로그•**탈출 경로 노출** | **장애 대응력** 확보 |
| 플랫폼 팀 **지원 병목** | 제품별 소유권•**SLO•문서 자동화** | **셀프서비스 지속성** 향상 |

#### 한줄 요약

- API 템플릿 자동화와 **실패 단계•원본 도구 상태 노출**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **인지부하**: 개발자가 업무 목표 외에 도구•인프라•정책을 이해하고 선택하는 데 드는 부담이다.
- **리드 타임**: 개발 요청부터 실행 환경•배포 결과가 준비될 때까지 걸린 시간이다.

</details>

- 플랫폼 엔지니어링의 핵심 산출물이자 개발자 경험(DevEx) 및 조직적 엔지니어링 생산성 혁신의 중심 축으로 확립된 **엔터프라이즈 셀프서비스 내부 개발자 플랫폼의 최고 표준(Internal Developer Platform: IDP / Spotify Backstage Open Standard / Golden Path Templates / Centralized Service Catalog & TechDocs / Policy-as-Code Guardrails)의 확고한 표준**으로 확고히 자리 잡았으며, AI 코딩 어시스턴트 및 클라우드 네이티브 자동화와 긴밀히 융합되는 가운데, 실무 엔터프라이즈 IDP 구축 시에는 **강제적 통제가 아닌 개발자의 자발적 채택을 유도하기 위해 명확한 골든 패스 템플릿과 단일 UI/CLI 포털을 제공하고, 표준을 벗어난 특수 워크로드를 수용하는 확장 지점(Extension & Escape Hatch)을 열어두며, DORA 메트릭 및 채택률(Adoption Rate) 기반의 지속적 플랫폼 개선**을 결합하여 완벽한 개발 생산성과 엔터프라이즈 거버넌스를 완성

#### 한줄 요약

- IDP의 성패는 기능 수가 아니라 표준 경로가 우회로보다 쉬운가에 달려 있으므로, **리드 타임•인지부하**가 실제로 줄지 않으면 팀은 곧 각자의 도구 조합으로 되돌아간다.
