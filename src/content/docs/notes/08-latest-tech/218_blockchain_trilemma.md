## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **블록체인 트릴레마(Blockchain Trilemma)**: 제한된 통신•저장•검증 자원 아래에서 탈중앙화•보안성•확장성을 동시에 극대화하기 어려운 상충 관계이다.

</details>

- 정의: **탈중앙화•보안성•확장성**을 동시에 극대화하기 어려운 상충 관계
- 배경/필요성: 처리량 증가에 따른 검증 비용 상승으로 **검증자 집중 위험**

#### 한줄 요약

- 세 목표의 **통신•저장•검증 비용** 간 균형점

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **탈중앙화**: 합의와 검증 권한이 특정 운영자에게 집중되지 않고 다양한 참여자에게 분산된 성질로 정의된다.
- **보안성**: 비잔틴 장애•경제적 공격에서도 합의 안전성과 장부 무결성•복구력을 유지하는 성질이다.
- **확장성**: 처리량을 높이고 확정 지연•수수료•저장 비용을 낮추면서 증가한 부하를 감당하는 성질을 의미한다.

</details>

- 검증자 수•다양성•집중도 기반 **탈중앙화**
- 공격 비용•합의 안전성•복구력 기반 **보안성**
- 처리량•확정 지연•수수료와 신뢰 가정 기반 **확장성**
#### 한줄 요약

- 처리량 향상에 따른 **검증 비용•신뢰 구조** 변화 평가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **합의 계층**: 여러 검증자가 거래 순서와 장부 상태에 동의하도록 규칙과 메시지 교환을 수행하는 구성요소로 정의된다.
- **제약 모델**: 목표 처리량•지연과 공격자 능력•신뢰 범위를 정의하여 세 속성의 평가 조건을 고정하는 모델이다.

</details>

```text
                       [제약 모델]
                     /       |       \
              [탈중앙화] ----- [보안성]
                     \           /
                       [확장성]
```

| 구성요소 | 책임 |
|:---|:---|
| 제약 모델 | **성능•공격 모델•신뢰 범위** 정의 |
| 탈중앙화 | **검증자 참여•노드 다양성** 평가 |
| 보안성 | **비잔틴 장애•경제적 공격** 통제 |
| 확장성 | **처리량•지연•저장 비용** 평가 |

#### 한줄 요약

- 목표 성능에 맞춘 **검증 조건•신뢰 비용** 평가

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **신뢰 가정**: 합의 참여자•시퀀서•브리지 중 어느 주체를 정직하다고 전제하는지 나타내는 조건이다.

</details>

```text
[업무 요구] ── 성능•신뢰 목표 ──▶ [평가 지표]
    │ 1. 처리량•지연•검증 비용 측정
    ▼
[L1•L2•샤딩 후보]
    │ 2. 확장 구조 설계
    ▼
[공격•장애 시험]
    │ 3. 보안성•탈중앙성 검증
    ▼
[구조 선택] ── 4. 운영 지표 환류 ──▶ [평가 지표]
```

### 동작 원리

1. 처리량•지연•검증 비용 측정: 동일 부하•공격 모델의 **기준선** 산정
2. 확장 구조 설계: L1•L2•샤딩별 **처리•정산•데이터 가용성** 배치
3. 보안성•탈중앙성 검증: **검증자 비용•시퀀서•브리지** 시험
4. 운영 지표 환류: 실제 **집중도•비용•장애**에 따른 구조 재조정

#### 한줄 요약

- 설계별 **비용•신뢰 이전**을 세 목표의 지표로 검증

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **계층 2(Layer 2, L2)**: 거래를 기본 블록체인 밖에서 처리한 뒤 결과와 증명을 계층 1에 정산하는 확장 계층이다.
- **계층 1(Layer 1, L1)**: 합의•실행•정산을 직접 수행하는 기본 블록체인 계층을 말한다.

</details>

| 구분 | L1 확장 | L2 롤업 | 모듈형•샤딩 |
|:---|:---|:---|:---|
| 적용 기준 | 기본 프로토콜의 **자체 성능 개선** | 응용 거래의 **대량 외부 처리•정산** | 실행•데이터•검증의 **작업 분할** |
| 핵심 특징 | 기본 계층의 **용량 확대** | 외부 처리 후 **L1 정산** | **데이터•실행 작업 분할** |
| 한계 | 검증 장비의 **고사양화** | **시퀀서•브리지 의존** | **교차 샤드•공유 보안** 복잡 |

#### 한줄 요약

- 계층별 **처리•검증 분리**에 따른 비용•신뢰 재배치

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **데이터 가용성**: 참여자가 블록이나 롤업 상태를 독립 검증하는 데 필요한 거래 데이터를 얻을 수 있는 성질을 의미한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 처리량 향상 뒤 **검증 중앙화** | 노드 비용•검증자 집중도 측정 | **탈중앙성 저하** 가시화 |
| L2 **시퀀서 장애•검열** | **강제 포함•다중 시퀀서•탈출 경로** | **가용성•검열 저항** 확보 |
| **평균 성능** 중심 선택 | **공격•과부하•데이터 가용성** 시험 | 실제 **보안 비용** 반영 |

#### 한줄 요약

- **시퀀서•브리지 위험**과 L1 검증•데이터 가용성 측정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **샤딩**: 장부와 처리 대상을 여러 조각으로 나눠 병렬 처리하여 확장성을 높이는 방식을 의미한다.

</details>

- **독립 검증•대량 처리•병렬 확장**에는 각각 **L1•L2•샤딩** 선택

#### 한줄 요약

- 성능 향상에 따른 **비용•보안 위험** 정량 검증
