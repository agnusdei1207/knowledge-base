## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **추론-행동(Reasoning and Acting, ReAct)**: 추론 단계에서 외부 행동(Action)을 선택하고, 관찰(Observation) 결과를 다음 추론에 반영하는 폐루프(Closed-loop) 실행 패턴. 정적 추론의 한계를 넘어 실시간 정보, 정밀 계산, 외부 상태 검증을 가능하게 하는 핵심 에이전트 아키텍처.

</details>

- 개념: 외부 관찰을 다음 추론에 반영하는 **ReAct 패턴**
- 배경: 내부 추론만으로는 **최신 외부 상태 검증 불가**

#### 한줄 요약
- 외부 도구 관찰 기반 **추론•행동 폐루프**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **관찰(Observation)**: 도구가 반환한 데이터·오류·상태를 구조화하여 다음 추론이 활용하도록 기록한 실행 결과. 출처·시점·신뢰도를 포함하여 근거 무결성 보장.
- **LLM(Large Language Model)**: 정보 공백을 분석하고 호출할 도구·인자를 추론해 행동 계획을 생성하는 엔진. 매 루프 관찰 재입력으로 가설 정제.
- **API(Application Programming Interface)**: 외부 도구 호출을 위한 표준 스키마·인자·응답 계약. 표준화된 호출과 권한·파라미터 검증으로 시스템 안전성 확보.
- **선택 축(Selection Axis)**: 정보 공백과 목표를 바탕으로 최적 도구와 구체적 인자를 결정하는 의사결정 단계.
- **관찰 축(Observation Axis)**: 도구 결과로부터 기존 가설의 정합성을 평가하고 행동을 수정·재선택하는 피드백 기전. 실패를 학습 신호로 전환하여 완성도 향상.

</details>

- **선택 축**: 정보 공백 기반 도구•인자 결정
- **관찰 축**: 결과•오류 기반 가설 평가와 행동 수정
- **통제 축**: 반복•근거•비용 기반 루프 종료

#### 한줄 요약
- **결과•오류**를 다음 추론에 반영하는 폐루프

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **행동 선택기(Action Selector)**: 현재 목표와 누적된 관찰을 바탕으로 호출할 도구의 종류와 인자를 결정하는 LLM 기반 의사결정 모듈을 뜻하며, 단발 응답이 아닌 다단계 루프에서 매 턴마다 재호출되어 외부 세계와의 상호작용 방향을 결정하는 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **데이터베이스(Database, DB)**: 외부 상태, 호출 이력, 관찰 결과를 영속적으로 저장하여 다음 추론의 근거로 제공하는 저장소이며, 단순 캐시가 아니라 출처·시점·트랜잭션 상태를 함께 관리해 후속 추론이 동일 관찰을 재현·참조할 수 있게 하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.

</details>

```text
[추론•정책] -- [행동 실행기] -- [관찰 처리기] -- [루프 제어기]
```

| 구성요소 | 주요 책임 |
|:---|:---|
| 추론/정책(Reasoning/Policy) | LLM 기반 정보 공백 분석 및 행동 선택 |
| 행동 실행기(Action Executor) | API 스키마 검증 및 권한 기반 실행 위임 |
| 관찰 처리기(Observation Processor) | 실행 결과의 출처·정상성 검증 및 DB 기록 |
| 루프 제어기(Loop Controller) | 종료 조건(비용, 시간, 근거 충분성) 기반 판정 |

#### 한줄 요약
- **추론•실행•관찰•제어** 기반 판단 구조

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **정보 공백·선택 행동 전달(Information Gap/Action Provision)**: 완료 조건과 현재 부족한 근거를 분석해 호출할 도구·인자 후보를 선정해 실행기에 전달하는 추론 단계이며, 이는 매 루프의 출발점으로 행동 방향을 결정하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **도구·인자·권한 검증 결과(Tool/Argument Verification)**: 호출 형식의 적합성·행동의 위험 등급·실행 권한의 보유 여부를 확인해 실행 가능 여부를 판정하는 단계이며, 검증 실패 시 실행을 차단해 시스템 안전성을 확보하는 실무적 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **검증된 도구 실행 요청(Verified Tool Request)**: 스키마·인자·권한이 모두 검증된 상태에서 제한된 샌드박스 환경 내 허가된 외부 행동을 수행하는 단계이며, 이는 비인가 행동을 원천 차단하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **실행 결과·오류 전달(Execution Result Return)**: 도구의 정상 출력뿐 아니라 실패 원인, 부분 결과, 오류 코드를 관찰 처리기로 전달하는 단계이며, 이는 성공·실패 양쪽 신호를 다음 추론에 동등하게 제공하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **도구/권한 검증**: 실행 가능성 판단 및 안전한 샌드박스 환경 제어.

</details>

```text
추론기(Reasoner)
    │ 1. 정보 공백·선택 행동 전달
    ├───────────────────┐
    │ 완료·중단 전까지   │
    └─────────┬─────────┘
    ▼
실행기(Executor)
    │ 2. 도구·인자·권한 검증 결과
    ▼
추론기(Reasoner)
    │ 3. 검증된 도구 실행 요청
    ▼
실행기(Executor)
    │ 4. 실행 결과·오류 전달
    ▼
관찰기(Observer)
    │ 5. 검증된 관찰 제공
    ▼
추론기(Reasoner)
```

### 동작 원리

1. **정보 공백·선택 행동 전달**: 부족 근거와 도구 후보 선정
2. **도구·인자·권한 검증 결과**: 형식•위험•권한 판정
3. **검증된 도구 실행 요청**: 허가된 행동 수행
4. **실행 결과·오류 전달**: 정상 출력•실패 원인 전송
5. **검증된 관찰 제공**: 출처•시점 검증 후 루프 반영

#### 한줄 요약
- **추론•행동•관찰** 5단계 폐루프 실행

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **사고 사슬(Chain of Thought, CoT)**: 외부 도구 실행 없이 문제를 중간 추론 단계로 분해해 각 단계의 논리를 명시적으로 펼친 뒤 최종 답을 도출하는 prompting 기법을 말하며, 외부 환경과 상호작용하지 않으므로 정적 지식 내 추론의 정확도를 높이는 데 특화된 실무적 안정성과 효율성을 보장하는 주요 기전이다.

</details>

| 판단 기준 | ReAct | 표준 프롬프팅 | 사고 사슬(CoT) |
|:---|:---|:---|:---|
| 적용 목적 | 외부 정보·계산 행동 루프 | 단순 질의 응답 | 논리·수학 단계 분해 |
| 핵심 기전 | 도구 관찰-추론 순환 | 단발 즉시 응답 | 내부 추론 논리 펼침 |
| 한계/단점 | 루프 비용 및 오류 전파 | 외부 상태 확인 불가 | 실시간 데이터 반영 불가 |

#### 한줄 요약
- 외부 상태는 **ReAct**, 내부 논리는 **CoT** 선택

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최대 반복 횟수(Max Iterations)**: 실행 루프의 무한 반복과 그로 인한 비용 폭증·지연 누적을 막기 위해 시스템이 허용하는 행동 횟수의 명시적 상한이며, 단순 안전장치가 아니라 비용-정확도 트레이드오프의 정책적 결정선을 제시하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **근거 충분성(Evidence Sufficiency)**: 수집한 관찰이 결론을 뒷받침하기에 충분하고, 추가 행동을 수행할 비용·시간 대비 정보 가치 향상이 미미한지를 판단하는 정량적·정성적 종료 기준을 뜻하며, 무한 정제(infinite refinement)를 방지해 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

| 문제 유형 | 대응 대책 | 기대 효과 |
|:---|:---|:---|
| 근거 오류 | 관찰 결과 출처 다축 검증 및 오류 재호출 | 연쇄 오류 방지 |
| 비용 폭증 | 최대 반복 횟수(Max Iterations) 및 조기 종료 | 무한 루프 억제 |
| 영향도 관리 | 변경/조회 권한 분리 및 다단계 승인 | 영향 범위(Blast Radius) 통제 |

#### 한줄 요약
- **최대 반복 횟수•근거 충분성** 기반 종료 통제

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **근거 충분성 기반 추론-행동 루프(Evidence-Sufficient Reasoning-Action Loop)**: 외부 상태 검증이 필요한 업무에는 **ReAct**를, 외부 의존 없이 내부 추론만으로 해결 가능한 문제에는 **CoT**를 업무 성격에 맞게 선택 적용하고, 두 경로 모두에서 **근거 충분성**과 **최대 반복 횟수**를 명시적 종료 조건으로 강제하는 실행 체계이며, 이는 hallucination을 억제하고 비용·정확도 트레이드오프를 통제하는 실무적 아키텍처 원칙이다.

</details>

- 외부 상태 검증은 **ReAct**, 내부 추론은 **CoT** 선택

#### 한줄 요약
- **외부 의존성•근거 충분성**에 따라 패턴과 종료 결정
