## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **추론-행동(Reasoning and Acting, ReAct)**: 모델이 추론으로 외부 행동을 선택하고 그 관찰 결과를 다음 추론에 반영하는 에이전트 실행 패턴이다.

</details>

- 정의/개념: 외부 행동의 관찰 결과를 다음 추론에 반영하는 **ReAct 패턴**이다.
- 배경/필요성: 모델 내부 추론만으로는 최신 정보•계산•외부 상태를 검증하기 어렵다.

#### 한줄 요약
- **ReAct**는 도구 관찰을 근거로 다음 행동을 결정한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **관찰**: 도구가 반환한 데이터•오류•외부 상태를 다음 추론이 사용할 수 있도록 기록한 실행 결과이다.
- **대규모 언어 모델(Large Language Model, LLM)**: 현재 목표와 정보 공백을 분석해 다음 행동 후보를 생성하는 추론 모델이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: ReAct가 외부 도구를 정해진 인자와 응답 형식으로 호출하는 인터페이스이다.
- **선택 축**: 정보 공백을 바탕으로 호출할 도구와 인자를 정하는 기능 영역이다.
- **관찰 축**: 도구의 근거•오류•외부 상태로 가설과 다음 행동을 수정하는 기능 영역이다.

</details>

- **선택 축**: **LLM** 추론 기반 **API** 도구•인자를 결정한다.
- **관찰 축**: 도구 근거•오류를 반영해 가설과 다음 행동 수정한다.
- 최대 반복 횟수•근거 충분성•비용•시간 기준으로 종료를 통제한다.

#### 한줄 요약
- **관찰 축**에서 도구 결과와 오류를 다음 추론에 반영한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **행동 선택기**: 현재 목표와 관찰을 바탕으로 호출할 도구와 인자를 결정하는 구성요소이다.
- **데이터베이스(Database, DB)**: 외부 상태와 관찰 결과를 저장하여 다음 추론의 근거로 제공하는 저장소이다.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 추론•정책 | **LLM**과 **행동 선택기**가 정보 공백•다음 행동 결정 |
| 행동 실행기 | **API** 스키마•인자•권한 검증 |
| 관찰 처리기 | **관찰**의 출처•오류를 **DB** 상태에 반영 |
| 루프 제어기 | 완료•비용•시간•반복 한도 제어 |

#### 한줄 요약
- **추론•실행•관찰•루프 제어**로 외부 근거 판단이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **정보 공백•선택 행동 전달**: 완료 조건과 부족한 근거를 분석해 도구•인자를 고르는 단계이다.
- **도구•인자•권한 검증 결과**: 호출 형식•행동 위험•실행 권한을 확인하는 단계이다.
- **검증된 도구 실행 요청**: 제한된 환경에서 허가된 외부 행동을 수행하는 단계이다.
- **실행 결과•오류 전달**: 도구 출력과 실패 원인을 관찰 처리기로 보내는 단계이다.
- **출처가 확인된 관찰 제공**: 근거를 다음 추론에 반영해 완료•재시도•중단을 판정하는 단계이다.

</details>

```text
추론기
   │ 1. 정보 공백•선택 행동 전달
   ├───────────────────┐
   │ 완료•중단 전까지 │
   └─────────┬─────────┘
   ▼
실행기
   │ 2. 도구•인자•권한 검증 결과
   ▼
추론기
   │ 3. 검증된 도구 실행 요청
   ▼
실행기
   │ 4. 실행 결과•오류 전달
   ▼
관찰기
   │ 5. 출처가 확인된 관찰 제공
   ▼
추론기
```

### 동작 원리

1. **정보 공백•선택 행동 전달**: 완료 조건과 부족한 근거를 분석해 도구•인자를 선택한다.
2. **도구•인자•권한 검증 결과**: 호출 형식과 행동 위험 및 실행 권한을 확인한다.
3. **검증된 도구 실행 요청**: 제한된 환경에서 허가된 외부 행동을 수행한다.
4. **실행 결과•오류 전달**: 도구 출력과 실패 원인을 관찰 처리기로 전송한다.
5. **출처가 확인된 관찰 제공**: 근거를 다음 추론에 반영해 완료•재시도•중단을 판정한다.

#### 한줄 요약
- **정보 공백•선택 행동 전달**부터 **출처가 확인된 관찰 제공**까지 반복한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **사고 사슬(Chain of Thought, CoT)**: 외부 도구 실행 없이 문제를 중간 추론 단계로 나누어 답을 도출하는 추론 기법이다.

</details>

| 판단 기준 | ReAct | 표준 프롬프팅 | Chain of Thought |
|:---|:---|:---|:---|
| 적용 기준 | **ReAct**는 외부 근거•행동 필요 | 표준 프롬프팅은 단순 질의•응답 필요 | **CoT**는 내부 추론 분해 필요 |
| 핵심 특징 | 추론•행동•관찰 반복 | 입력 후 단발 응답 | 내부 추론 후 응답 |
| 한계 | 반복 비용•도구 오류 누적 | 외부 상태 확인 불가 | 외부 행동•관찰 부족 |

> 요약: **ReAct** 중심 외부 행동, **표준 프롬프팅•CoT** 중심 단발•내부 추론이 핵심이다.

#### 한줄 요약
- 단발은 표준 프롬프팅, 내부 추론은 **CoT**, 도구 관찰은 **ReAct**가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **최대 반복 횟수**: 실행 루프의 무한 반복과 비용 증가를 막기 위해 허용하는 행동 횟수의 상한이다.
- **근거 충분성**: 수집한 관찰이 결론을 뒷받침하고 추가 행동의 비용보다 충분한지를 판단하는 종료 기준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신뢰할 수 없는 결과로 생기는 환각 강화 | **관찰**의 출처•시점•오류 상태 검증 | 잘못된 근거 반영 방지 |
| 반복 루프로 발생하는 비용 누적 | **최대 반복 횟수**와 **근거 충분성** 기준 설정 | 무한 실행 억제 |
| 계정 초기화의 고위험 상태 변경 | 조회•변경 권한 분리•본인확인•승인 적용 | 외부 행동의 영향 범위 통제 |

#### 한줄 요약
- **최대 반복 횟수**와 상태 변경 승인 경계를 함께 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

</details>

- 외부 상태•행동은 **ReAct**, 내부 추론은 **CoT**을 선택한다.

#### 한줄 요약
- **근거 충분성**과 반복 한도를 갖춘 ReAct 루프를 적용한다.
