## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **추론-행동(Reasoning and Acting, ReAct)**: 모델이 추론 단계에서 외부 행동을 선택하고, 그 관찰 결과를 다시 다음 추론에 반영하는 폐루프(closed-loop) 에이전트 실행 패턴을 의미하며, 정적 추론만으로는 접근할 수 없는 최신 정보·정확한 계산·외부 상태 검증까지 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- 정의/개념: 외부 행동의 관찰 결과를 다음 추론에 반영하는 **ReAct 패턴**임. 이는 모델 내부 추론과 외부 도구 실행을 결합해 단발 응답의 한계를 극복하고, 근거 기반 의사결정의 신뢰성을 확보하는 점에서 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 배경/필요성: 모델 내부 추론만으로는 학습 시점 이후의 최신 정보, 복잡한 산술 계산, 그리고 실시간 외부 상태를 검증하기 어려워, hallucination을 줄이고 업무 정확도를 높이려면 외부 관찰을 추론에 연결하는 메커니즘이 필수이기 때문임.

#### 한줄 요약
- **ReAct**는 도구 관찰을 근거로 다음 행동을 결정하는 추론-행동 통합 패턴 적용

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **관찰(Observation)**: 도구가 반환한 데이터·오류·외부 상태를 구조화된 형태로 다음 추론이 즉시 활용할 수 있도록 기록한 실행 결과이며, 이는 단순 텍스트가 아니라 출처·시점·신뢰도까지 포함해 추론의 근거 무결성을 보장하는 기술적 기반이 된다.
- **대규모 언어 모델(Large Language Model, LLM)**: 현재 목표 달성에 필요한 정보 공백(information gap)을 분석하고 후보 도구·인자 조합을 추론해 다음 행동 계획을 생성하는 추론 엔진이며, 매 루프마다 관찰을 재입력받아 점진적으로 가설을 정제하는 점에서 실무적 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: ReAct 에이전트가 외부 도구를 호출할 때 사용하는 정해진 스키마·인자·응답 형식의 계약(contract) 인터페이스이며, 이는 호출 형식의 표준화와 권한·파라미터 검증을 강제해 시스템적 안전성과 차별화된 성능을 제공하는 기술적 기반이 된다.
- **선택 축(Selection Axis)**: 현재 정보 공백과 목표를 바탕으로 호출할 도구의 종류와 구체적 인자를 결정하는 추론의 기능 영역으로, LLM이 단독으로 도구 선택과 파라미터 구성을 책임지는 의사결정 단계를 지칭한다.
- **관찰 축(Observation Axis)**: 도구의 정상 결과·오류 메시지·외부 상태 변화로부터 기존 가설의 정합성을 평가하고 다음 행동을 수정·재선택하는 피드백 기능 영역이며, 이는 정적 추론과 달리 실패를 학습 신호로 전환해 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **선택 축**: **LLM** 추론이 정보 공백을 분석해 호출할 **API** 도구와 인자를 결정하며, 도구 카탈로그와 권한 메타데이터를 바탕으로 실행 가능한 행동 후보를 한정하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **관찰 축**: 도구의 결과와 근거·오류를 반영해 기존 가설의 정합성을 재평가하고 다음 행동을 수정·재선택하며, 이를 통해 실패를 학습 신호로 전환하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- 종료 통제: 최대 반복 횟수·근거 충분성·누적 비용·경과 시간의 다축(multi-axis) 기준을 종합 판정해 루프를 종료하며, 단순 상한만 두는 것과 달리 비용-정확도 트레이드오프를 명시적으로 관리하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **관찰 축**에서 도구 결과와 오류를 다음 추론에 반영하는 폐루프 피드백 적용

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **행동 선택기(Action Selector)**: 현재 목표와 누적된 관찰을 바탕으로 호출할 도구의 종류와 인자를 결정하는 LLM 기반 의사결정 모듈을 뜻하며, 단발 응답이 아닌 다단계 루프에서 매 턴마다 재호출되어 외부 세계와의 상호작용 방향을 결정하는 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **데이터베이스(Database, DB)**: 외부 상태, 호출 이력, 관찰 결과를 영속적으로 저장하여 다음 추론의 근거로 제공하는 저장소이며, 단순 캐시가 아니라 출처·시점·트랜잭션 상태를 함께 관리해 후속 추론이 동일 관찰을 재현·참조할 수 있게 하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.

</details>

| 구성요소 | 책임 |
|:---|:---|
| 추론·정책 | **LLM**과 **행동 선택기**가 정보 공백을 분석하고 다음 행동을 결정함 |
| 행동 실행기 | **API** 스키마·인자 유효성·권한 범위를 검증해 실행을 위임함 |
| 관찰 처리기 | **관찰**의 출처·정상 여부·오류 코드를 **DB** 상태에 기록·갱신함 |
| 루프 제어기 | 완료 조건·누적 비용·경과 시간·반복 한도를 종합 판정해 종료함 |

#### 한줄 요약
- **추론·실행·관찰·루프 제어** 4요소 기반 외부 근거 판단 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **정보 공백·선택 행동 전달(Information Gap/Action Provision)**: 완료 조건과 현재 부족한 근거를 분석해 호출할 도구·인자 후보를 선정해 실행기에 전달하는 추론 단계이며, 이는 매 루프의 출발점으로 행동 방향을 결정하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **도구·인자·권한 검증 결과(Tool/Argument Verification)**: 호출 형식의 적합성·행동의 위험 등급·실행 권한의 보유 여부를 확인해 실행 가능 여부를 판정하는 단계이며, 검증 실패 시 실행을 차단해 시스템 안전성을 확보하는 실무적 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **검증된 도구 실행 요청(Verified Tool Request)**: 스키마·인자·권한이 모두 검증된 상태에서 제한된 샌드박스 환경 내 허가된 외부 행동을 수행하는 단계이며, 이는 비인가 행동을 원천 차단하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **실행 결과·오류 전달(Execution Result Return)**: 도구의 정상 출력뿐 아니라 실패 원인, 부분 결과, 오류 코드를 관찰 처리기로 전달하는 단계이며, 이는 성공·실패 양쪽 신호를 다음 추론에 동등하게 제공하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **출처가 확인된 관찰 제공(Verified Observation Provision)**: 관찰의 출처·시점·신뢰도를 검증한 뒤 다음 추론에 반영해 완료·재시도·중단을 판정하는 단계이며, 이는 정적 응답을 벗어나 외부 근거에 기반한 의사결정을 가능하게 하는 자율적 판단과 실행의 핵심 아키텍처 요소이다.

</details>

추론기
   │ 1. 정보 공백•선택 행동 전달
   ├───────────────────┐
   │ 완료•중단 전까지 │

   ▼

   │ 3. 검증된 도구 실행 요청

   ▼

   ▼

### 동작 원리

1. **정보 공백·선택 행동 전달**: 완료 조건과 부족한 근거를 분석해 호출할 도구·인자를 선택해 실행기에 전달함.
2. **도구·인자·권한 검증 결과**: 호출 형식의 적합성, 행동 위험 등급, 실행 권한 보유 여부를 확인해 실행 가능 여부를 판정함.
3. **검증된 도구 실행 요청**: 스키마·인자·권한이 모두 검증된 상태에서 제한된 샌드박스 환경 내 허가된 외부 행동을 수행함.
4. **실행 결과·오류 전달**: 정상 출력뿐 아니라 실패 원인·부분 결과·오류 코드까지 관찰 처리기로 전송함.
5. **출처가 확인된 관찰 제공**: 관찰의 출처·시점·신뢰도를 검증한 뒤 다음 추론에 반영해 완료·재시도·중단을 판정함.

- **정보 공백·선택 행동 전달**부터 **출처가 확인된 관찰 제공**까지 5단계 폐루프 반복 적용

## �. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **사고 사슬(Chain of Thought, CoT)**: 외부 도구 실행 없이 문제를 중간 추론 단계로 분해해 각 단계의 논리를 명시적으로 펼친 뒤 최종 답을 도출하는 prompting 기법을 말하며, 외부 환경과 상호작용하지 않으므로 정적 지식 내 추론의 정확도를 높이는 데 특화된 실무적 안정성과 효율성을 보장하는 주요 기전이다.

</details>

| 판단 기준 | ReAct | 표준 프롬프팅 | Chain of Thought |
|:---|:---|:---|:---|
| 적용 기준 | **ReAct**는 최신 정보·정확한 계산 등 외부 근거·행동이 필요한 업무에 적용함 | 표준 프롬프팅은 단순 질의·단발 응답 수준의 업무에 적용함 | **CoT**는 외부 의존 없이 내부 추론 분해가 필요한 논리·수학 문제에 적용함 |
| 핵심 특징 | 추론·행동·관찰을 루프로 반복해 외부 근거를 누적함 | 입력 후 단발로 응답하며 외부 상호작용이 없음 | 내부 추론 단계만 펼친 뒤 단발로 응답함 |
| 한계 | 반복 횟수만큼 LLM 호출 비용이 누적되고 도구 오류가 다음 추론에 전파될 위험이 있음 | 외부 상태·실시간 정보 확인이 불가해 hallucination 위험이 큼 | 외부 행동·관찰이 부재해 최신 정보 반영이나 실제 환경 검증이 불가함 |

> 요약: **ReAct**는 외부 행동 기반 추론-행동 루프, **표준 프롬프팅·CoT**는 단발 응답과 내부 추론 분해가 각각 핵심임.

#### 한줄 요약
- 단발은 표준 프롬프팅, 내부 추론 분해는 **CoT**, 도구 관찰 기반 루프는 **ReAct** 선택 적용

## Ⅵ. 실무 고려사항 및对策

<details>
<summary>핵심 용어</summary>

- **최대 반복 횟수(Max Iterations)**: 실행 루프의 무한 반복과 그로 인한 비용 폭증·지연 누적을 막기 위해 시스템이 허용하는 행동 횟수의 명시적 상한이며, 단순 안전장치가 아니라 비용-정확도 트레이드오프의 정책적 결정선을 제시하는 구조적 완결성과 차별화된 성능의 기술적 기반이 된다.
- **근거 충분성(Evidence Sufficiency)**: 수집한 관찰이 결론을 뒷받침하기에 충분하고, 추가 행동을 수행할 비용·시간 대비 정보 가치 향상이 미미한지를 판단하는 정량적·정성적 종료 기준을 뜻하며, 무한 정제(infinite refinement)를 방지해 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신뢰할 수 없는 결과로 생기는 환각 강화 | **관찰**의 출처·시점·오류 상태를 다축으로 검증하고 의심스러운 결과는 폐기·재호출함 | 잘못된 근거가 후속 추론에 반영되는 연쇄 오류를 방지함 |
| 반복 루프로 발생하는 비용 누적 | **최대 반복 횟수** 상한과 **근거 충분성** 기준을 동시에 설정해 조기 종료 조건을 마련함 | 무한 실행과 비용 폭증을 억제함 |
| 계정 초기화 같은 고위험 상태 변경 | 조회 권한과 변경 권한을 분리하고, 본인확인·다단계 승인을 적용함 | 외부 행동의 영향 범위와 blast radius를 통제함 |

#### 한줄 요약
- **최대 반복 횟수** 상한과 상태 변경 승인 경계를 함께 적용한 안전장치 체계 구현

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **근거 충분성 기반 추론-행동 루프(Evidence-Sufficient Reasoning-Action Loop)**: 외부 상태 검증이 필요한 업무에는 **ReAct**를, 외부 의존 없이 내부 추론만으로 해결 가능한 문제에는 **CoT**를 업무 성격에 맞게 선택 적용하고, 두 경로 모두에서 **근거 충분성**과 **최대 반복 횟수**를 명시적 종료 조건으로 강제하는 실행 체계이며, 이는 hallucination을 억제하고 비용·정확도 트레이드오프를 통제하는 실무적 아키텍처 원칙이다.

</details>

- 외부 상태·행동 검증이 필요한 업무에는 **ReAct**, 외부 의존 없이 내부 추론만으로 충분한 문제에는 **CoT**를 업무 성격에 맞게 선택 적용하여, 단일 패턴에 강제하지 않음으로써 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **근거 충분성**과 반복 한도를 갖춘 추론-행동 루프의 업무별 선택적 적용 원칙 준수
