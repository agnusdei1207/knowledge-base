## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ReAct 패턴(Reasoning and Acting)**: 대규모 언어 모델이 추론(Thought)을 바탕으로 외부 도구 행동(Action)을 수행하고, 관찰(Observation) 결과를 다음 추론에 반영하는 폐루프(Closed-loop) 에이전트 패턴.
- **자율 에이전트(Autonomous Agent)**: 고정된 프롬프트 응답을 넘어 실시간 웹 검색, API 호출, DB 조회를 자율적으로 조합하여 복합 문제를 해결하는 지능형 시스템.

</details>

- 개념: 외부 관찰을 다음 추론에 반영하는 **ReAct 패턴**
- 배경: 내부 추론만으로는 **최신 외부 상태 검증 불가**

#### 한줄 요약
- 외부 도구 관찰 기반 **추론•행동 폐루프**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **관찰(Observation)**: 외부 도구가 반환한 데이터, 상태값, 에러 메시지를 다음 추론 단계의 새로운 입력 컨텍스트로 통합하는 메커니즘.
- **대규모 언어 모델(Large Language Model, LLM)**: 목표 분석, 정보 공백 파악, 최적 도구 선택 및 인자 생성을 전담하는 중앙 추론 엔진.
- **도구 인터페이스(Tool API)**: 계산기, 검색 엔진, 코드 인터프리터 등 외부 환경과 상호작용하기 위해 정의된 표준 함수 계약.
- **선택 및 관찰 축(Selection & Observation Axes)**: 가설 수립(추론)과 실측 데이터 획득(행동/관찰)을 상호 보완적으로 교차 반복하는 2축 구조.

</details>

- **선택 축**: 정보 공백 기반 도구•인자 결정
- **관찰 축**: 결과•오류 기반 가설 평가와 행동 수정
- **통제 축**: 반복•근거•비용 기반 루프 종료

#### 한줄 요약
- **결과**•**오류**를 다음 추론에 반영하는 폐루프

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Thought-Action-Observation 루프**: LLM이 사고(Thought)로 계획을 세우고, 행동(Action)으로 도구를 호출하며, 관찰(Observation)로 결과를 받아 다음 단계를 결정하는 반복 구조이다.
- **최종 답변(Final Answer)**: 충분한 근거가 확보되어 루프를 종료하고 사용자에게 반환하는 최종 출력이다.

</details>

```text
[추론•정책] -- [행동 실행기] -- [관찰 처리기] -- [루프 제어기]
```

| 구성요소 | 주요 책임 |
|:---|:---|
| 추론/정책(Reasoning/Policy) | LLM 기반 정보 공백 분석 및 행동 선택 |
| 행동 실행기(Action Executor) | API 스키마 검증 및 권한 기반 실행 위임 |
| 관찰 처리기(Observation Processor) | 실행 결과의 출처·정상성 검증 및 DB 기록 |
| 루프 제어기(Loop Controller) | 종료 조건(비용, 시간, 근거 충분성) 기반 판정 |

#### 한줄 요약
- **추론•실행•관찰•제어** 기반 판단 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **추론 생성(Thought Generation)**: 현재 상태를 분석하고 다음 필요한 정보와 행동 목표를 자연어로 사고하는 단계.
- **행동 호출(Action Execution)**: 사전 정의된 도구 스키마에 맞춰 구조화된 함수 호출을 수행하는 단계.
- **결과 관찰(Observation Intake)**: 도구 반환값을 수신하고 오류 유무 및 정보 적합성을 확인하는 단계.
- **피드백 반영(Feedback Loop)**: 관찰 결과를 기존 가설과 대조하여 최종 답변 생성 또는 다음 루프를 지속하는 단계.

</details>

```text
추론기(Reasoner)
    │ 1. 정보 공백·선택 행동 전달
    ├───────────────────┐
    │ 완료·중단 전까지   │
    └─────────┬─────────┘
    ▼
실행기(Executor)
    │ 2. 도구·인자·권한 검증 결과
    ▼
추론기(Reasoner)
    │ 3. 검증된 도구 실행 요청
    ▼
실행기(Executor)
    │ 4. 실행 결과·오류 전달
    ▼
관찰기(Observer)
    │ 5. 검증된 관찰 제공
    ▼
추론기(Reasoner)
```

### 동작 원리

1. **정보 공백·선택 행동 전달**: 부족 근거와 도구 후보 선정
2. **도구·인자·권한 검증 결과**: 형식•위험•권한 판정
3. **검증된 도구 실행 요청**: 허가된 행동 수행
4. **실행 결과·오류 전달**: 정상 출력•실패 원인 전송
5. **검증된 관찰 제공**: 출처•시점 검증 후 루프 반영

#### 한줄 요약
- **추론•행동•관찰** 5단계 폐루프 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사고 사슬(Chain of Thought, CoT)**: 외부 환경과 상호작용 없이 내부 지식만으로 단계별 추론을 전개하여 환각(Hallucination)에 취약한 방식.
- **ReAct 패턴(Reasoning and Acting)**: 외부 도구 관찰을 추론 사슬에 지속 피드백하여 최신성, 정확성, 검증 가능성을 보장하는 방식.

</details>

| 판단 기준 | ReAct | 표준 프롬프팅 | 사고 사슬(CoT) |
|:---|:---|:---|:---|
| 적용 기준 | 외부 정보·계산 행동 루프 | 단순 질의 응답 | 논리·수학 단계 분해 |
| 핵심 특징 | 도구 관찰-추론 순환 | 단발 즉시 응답 | 내부 추론 논리 펼침 |
| 한계 | 루프 비용 및 오류 전파 | 외부 상태 확인 불가 | 실시간 데이터 반영 불가 |

#### 한줄 요약
- 외부 상태는 **ReAct**, 내부 논리는 **CoT** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **최대 반복 횟수 제한(Max Iterations Safeguard)**: 무한 루프 진입으로 인한 API 비용 폭증과 응답 지연을 방지하기 위해 최대 호출 횟수(예: 5~10회) 강제 설정.
- **도구 호출 오류 복구(Tool Error Recovery)**: API 호출 실패나 JSON 파싱 에러 발생 시 오류 메시지를 관찰로 넘겨 자율 재시도 유도.
- **컨텍스트 윈도우 관리(Context Window Optimization)**: 루프 반복 시 누적되는 토큰 수를 제어하기 위해 중간 관찰 요약(Summarization) 적용.

</details>

| 문제 유형 | 대응 대책 | 기대 효과 |
|:---|:---|:---|
| 근거 오류 | 관찰 결과 출처 다축 검증 및 오류 재호출 | 연쇄 오류 방지 |
| 비용 폭증 | 최대 반복 횟수(Max Iterations) 및 조기 종료 | 무한 루프 억제 |
| 영향도 관리 | 변경/조회 권한 분리 및 다단계 승인 | 영향 범위(Blast Radius) 통제 |

#### 한줄 요약
- **최대 반복 횟수•근거 충분성** 기반 종료 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동적 환경 적응형 AI 에이전트(Dynamic Adaptive AI Agent)**: 추론과 행동의 유기적 결합을 통해 정적 언어 모델의 한계를 극복하고 복잡한 엔터프라이즈 업무를 자율 수행하는 핵심 아키텍처.

</details>

- 외부 상태 검증은 **ReAct**, 내부 추론은 **CoT** 선택

#### 한줄 요약
- **외부 의존성•근거 충분성**에 따라 패턴과 종료 결정
