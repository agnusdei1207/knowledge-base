## 미리 알고가기

- **간접 프롬프트 인젝션**: 사용자 입력이 아닌 외부 문서나 웹 콘텐츠에 숨은 명령이 LLM을 오염시키는 공격
- **RAG(검색 증강 생성)**: RAG·브라우징·메일 등 외부 콘텐츠를 읽는 구조에서 특히 위험함
- **문서 정화**: 문서 정화와 아웃바운드 권한 통제가 핵심 방어 지점임



## Ⅰ. 개요

- **정의/개념**: 외부 콘텐츠의 숨은 지시로 모델을 조종하는 공격이다
- **배경/필요성**: 외부 자료와 내부 지시의 혼동 피해를 막는다

### 쉽게 이해하기 (학습용)
- 메일 본문에 내부 문서 전송 명령을 숨겨 요약 AI가 실행하도록 유도한다.

## Ⅱ. 특징

- 공격자는 대화 없이 제3자 콘텐츠로 지시를 주입한다
- 문맥의 지시·데이터 혼동은 숨은 명령을 실행시킨다
- 자동 검색은 정상 질의에 악성 지시를 결합한다
- 도구 권한은 조회·전송 피해를 확대한다
- 독립 권한 검증은 콘텐츠 탐지 실패의 피해를 막는다

### 쉽게 이해하기 (학습용)
- 자료의 출처와 그 자료가 요구한 행동 권한을 서로 다른 경계에서 검사한다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 출처 라벨 | 콘텐츠 원천·소유자·검증 여부를 메타데이터로 전달 |
| 신뢰 구역 | 외부 콘텐츠를 지시와 분리하여 데이터 구역으로 조립 |
| 정책 판정 | 모델 계획과 사용자 목적의 일치성 검사 |
| 도구 게이트 | 도구 호출 전 권한 검증 및 고위험 작업 승인 |
| 반출 검사 | 응답·API 호출의 민감 정보 및 목적지 검사 |

> 요약: 출처·문맥·도구·반출 경계에서 외부 지시를 차단한다

### 쉽게 이해하기 (학습용)
- 자료의 출처를 표시하고 데이터 구역으로 분리한 뒤 행동 제안은 권한 문지기를 통과한다.

## Ⅳ. 원리 및 절차 흐름도

```text
수집 → 데이터 조립 → 응답 계획
           ↓
독립 검증 → 허용 분기 → 실행·응답
```

| 절차 | 설명 |
|:---|:---|
| 콘텐츠 수집 | 검색·웹·메일 등 외부 입력을 식별함 |
| 구역 분리 | 외부 텍스트를 지시가 아닌 데이터로 조립함 |
| 계획 검증 | 응답과 도구가 요청 목적에 부합하는지 판정함 |
| 권한 게이트 | 실행 전 최소 권한 및 사용자 승인을 확인함 |
| 외부 검증 | 민감 정보와 수신 목적지 검사 후 실행함 |

> 요약: 외부 자료를 분리하고 행동 권한과 반출을 검증한다

### 쉽게 이해하기 (학습용)
- 외부 자료를 읽은 AI의 행동은 원래 요청과 권한을 다시 확인한 뒤 실행된다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 직접 인젝션 | 간접 인젝션 |
|:---|:---|:---|
| 공격 경로 | 대화창에 지시를 직접 제출함 | 웹·문서·메일 등에 지시 삽입 |
| 영향 범위 | 공격자 세션 내 즉시 정책 변경 | 제3자 세션서 지연 발동 후 확산 |
| 적용 기준 | 요청과 정책 충돌 여부 판정 | 출처 신뢰도와 도구 반출 권한 판정 |

> 요약: 직접은 대화, 간접은 외부 자료로 지시를 주입한다

### 쉽게 이해하기 (학습용)
- 직접 공격은 채팅창에 명령을 넣고 간접 공격은 외부 자료에 명령을 숨긴다.

## Ⅵ. 실무 사례

1. 사내 RAG는 외부 문서의 내부 조회 시도를 차단한다
2. 메일 에이전트는 수신자·데이터를 승인 뒤 전송한다

### 쉽게 이해하기 (학습용)

- 검색 문서의 숨은 지시가 내부 자료를 요구해도 업무 정책이 조회 권한을 다시 확인한다.
- 메일 본문의 지시가 외부 전송을 요구해도 수신자와 데이터를 사용자가 승인한다.

## Ⅶ. 결론

- 외부 콘텐츠와 도구 권한을 분리해 반출을 검증한다.

### 쉽게 이해하기 (학습용)

- 공격 문장을 알아맞히기보다 비신뢰 자료가 중요 행동을 직접 결정하지 못하게 설계한다.
