## 미리 알고가기

- **키·값(Key-Value, KV, 케이브이) 캐시**: 어텐션의 키·값 머리글자를 딴 명칭으로, 이전 토큰의 K·V를 재사용
- **대규모 언어모델(LLM)**: KV 캐시를 사용하는 생성 모델
- **그래픽 처리장치(GPU)**: 모델 연산과 캐시 접근 수행
- **중앙처리장치(CPU)**: 캐시 오프로딩 계층으로 활용
- **비디오 메모리(VRAM)**: KV 캐시를 저장하는 GPU 메모리
- **다중 헤드 어텐션(MHA)**: 헤드별 키·값을 저장
- **그룹 질의 어텐션(GQA)**: 여러 질의 헤드가 키·값 공유
- **다중 질의 어텐션(MQA)**: 모든 질의 헤드가 키·값 공유
- **최소 최근 사용(LRU)**: 오래 안 쓴 캐시 우선 회수
- **유효 시간(TTL)**: 캐시 보존 시간 제한
- **핵심 판단**: 재계산 감소와 메모리 비용 최적화 균형 중시



## Ⅰ. 개요

- 정의/개념: 이전 토큰 K·V 재사용·메모리 관리
- 기존 한계: 자기회귀 생성은 이전 토큰 K·V 재계산 비용 발생
- 기존 한계: 자기회귀 생성에서 이전 토큰의 Key·Value를 매번 다시 계산하면 긴 문맥일수록 연산량과 메모리 사용이 급증한다.

### 쉽게 이해하기 (학습용)

- 이전 계산 재사용을 위해 메모해 두되, 문장 증가에 따른 공간 부족 문제 대응

## Ⅱ. 특징

- 이전 토큰의 K·V를 저장해 디코드 재계산을 제거한다
- 캐시 크기는 층·KV 헤드·토큰·배치·정밀도에 비례한다
- GQA·MQA·양자화·페이징으로 메모리 부담을 줄인다

### 쉽게 이해하기 (학습용)

- 메모 절약, 앞부분 공유, 부족 시 회수/지움 수행

### 쉽게 이해하기 (학습용)

- 계산 결과를 층별 블록에 저장하고 토큰마다 추가함

### 쉽게 이해하기 (학습용)

- 요청 전 용량을 계산하고 부족하면 회수·이동함

## Ⅴ. 종류 및 비교

| 판단 기준 | KV 캐시 미사용 | KV 캐시 사용 |
|:---|:---|:---|
| 적용 기준 | 매우 짧은 생성·메모리 제약 | 일반 자기회귀 LLM 서빙 |
| 핵심 특징 | 과거 K·V를 매번 재계산 | 저장된 K·V 재사용 |
| 한계 | 디코드 연산량 증가 | 메모리 용량 증가 |

> 요약: 캐시는 재계산 비용을 메모리 사용과 교환함

### 쉽게 이해하기 (학습용)

- 계산을 다시 하는 비용과 계산 결과를 저장하고 읽는 비용 사이의 선택임

## Ⅵ. 실무 사례

- 장문/테넌트별 메모리·히트율·대역폭 측정

### 쉽게 이해하기 (학습용)

- 메모 절약/지움 시 정보 정밀도 및 재계산 시간 발생

## Ⅶ. 결론

- 자기회귀 생성의 이전 토큰 재계산을 줄이기 위해 **문맥 길이·동시 요청·메모리 용량·캐시 정밀도·폐기 정책**을 검토하고, 지연과 처리량 개선에 KV Cache 최적화를 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 빠른 생성을 위해 남기는 메모가 서버의 가장 큰 자원이 될 수 있어 수명주기 관리가 필요함
