## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 K•V 벡터를 저장하여 다음 토큰의 어텐션에서 재사용하는 메모리다.
- **자기회귀 생성(Autoregressive Generation)**: 앞서 생성한 토큰을 문맥에 포함해 다음 토큰을 하나씩 만드는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- 정의/개념: 키•값 재사용과 저장•회수로 메모리를 관리하는 **KV Cache 최적화**
- 배경/필요성: 장문•동시 요청으로 **반복 계산•캐시 메모리 증가**

#### 한줄 요약
- **키•값 재사용**과 캐시 용량•수명 관리

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **키-값 헤드(Key-Value Head, KV Head)**: 어텐션에서 토큰별 키(Key, K)•밸류(Value, V) 벡터를 생성하고 캐시에 저장하는 헤드다.
- **캐시 용량**: 모델 층•KV 헤드•토큰•배치 수•수치 정밀도에 비례해 필요한 메모리 크기다.
- **디코드 재계산 제거**: 저장한 과거 K•V를 재사용하여 매 토큰 생성 때 이전 문맥을 다시 계산하지 않는 효과다.
- **그룹 쿼리 어텐션(Grouped-Query Attention, GQA)**: Q 그룹별로 K•V 헤드를 공유하는 구조다.
- **멀티 쿼리 어텐션(Multi-Query Attention, MQA)**: 모든 Q 헤드가 단일 K•V 헤드를 공유하는 구조다.

</details>

![Observable Plot으로 그린 문맥 길이•KV 헤드 수별 캐시 메모리 이론값](/study/diagrams/kv-cache-memory.svg)

> 문맥이 길어질수록 세 선은 비례 증가하지만 KV 헤드를 공유하는 GQA•MQA의 기울기가 MHA보다 작으며, 32층•BF16 가정의 이론값이다.

- **디코드 재계산 제거**: 과거 키•값 재사용
- **캐시 용량**: 층•KV Head•토큰•배치•정밀도에 비례
- **GQA**: Q 그룹별 K•V 공유로 캐시 절감
- **MQA**: 단일 K•V 공유로 캐시 최소화
- **양자화**: 저정밀 표현으로 캐시 용량 축소
- **페이징**: 블록 할당으로 단편화 완화

#### 한줄 요약
- **문맥•배치•KV Head•정밀도**에 비례한 캐시 증가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **블록 할당기**: 요청별 캐시 공간을 작은 블록 단위로 동적 배정하고 종료 후 반납하는 구성요소다.
- **캐시 레이아웃**: 계층•헤드•토큰별 키•값을 메모리에 배치하고 논리 순서와 실제 주소를 연결하는 구조다.
- **압축 계층**: 키•값의 정밀도•헤드•토큰 보존 범위를 줄여 캐시 용량과 대역폭을 절감하는 구성요소다.
- **접두사 공유**: 여러 요청의 동일 입력 앞부분에 대한 K•V 캐시를 함께 참조하여 중복 저장과 계산을 줄이는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **GPU(Graphics Processing Unit)**: KV Cache 연산과 저장을 가속하는 병렬 처리장치다.
- **CPU(Central Processing Unit)**: 오프로딩 캐시를 보관할 수 있는 범용 처리장치다.
- **오프로딩(Offloading)**: 캐시 일부를 GPU 메모리에서 CPU 메모리 같은 하위 계층으로 이동하는 방법을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **캐시 스케줄러**: 요청 우선순위•가용 메모리•재사용 가능성을 바탕으로 할당•축출•오프로딩을 조정하는 구성요소다.

</details>

```text
                 [캐시 레이아웃]
                         |
                   [블록 할당기]
                         |
                    [압축 계층]
                         |
                   [재사용•회수]
                         |
                     [스케줄러]
```

선의 의미: 캐시 레이아웃을 블록 할당기와 압축 계층이 관리하고, 재사용•회수 및 스케줄러가 메모리 수명과 자원 경계를 통제하는 KV Cache 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 캐시 레이아웃 | 층•요청•**KV Head•토큰별 저장 형상 정의** |
| 블록 할당기 | 요청별 캐시 공간의 **동적 할당•반납** |
| 압축 계층 | KV 공유•양자화로 **표현 용량 축소** |
| 재사용•회수 | 공통 접두사 공유와 종료 캐시의 **수명 관리** |
| 스케줄러 | 메모리 여유에 따른 **요청 수용•선점•오프로딩** |

#### 한줄 요약
- **레이아웃•할당•압축•회수•스케줄링** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프리필 캐시**: 입력 토큰 전체를 병렬 처리하여 생성 전에 구성한 초기 K•V 상태다.
- **캐시 회수**: 요청 종료나 선점 뒤 더 이상 참조하지 않는 블록을 반납하여 가용 메모리를 복원하는 과정이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

```text
스케줄러
    │ 1. 요청별 캐시 용량 산정
    ▼
할당기
    │ 2. 캐시 블록 동적 할당
    ▼
KV Cache
    │ 3. 프리필 키•값 저장
    ▼
┌────────── 생성 종료 전 반복 ──────────┐
│ KV Cache                              │
│   └ 4. 과거 키•값 조회•신규 값 추가  │
└───────────────────────────────────────┘
    │ 요청 종료 통보
    ▼
할당기
    │ 5. 캐시 블록 회수
    ▼
KV Cache
```

### 동작 원리

1. **요청별 캐시 용량 산정**: 문맥•층•**KV Head•정밀도** 기반 메모리 계산
2. **캐시 블록 동적 할당**: 가용 메모리에서 요청에 필요한 **저장 영역**을 배정함.
3. **프리필 키•값 저장**: 입력 토큰별 키•값을 계산해 **초기 캐시**를 구성함.
4. **과거 키•값 조회•신규 값 추가**: 디코드마다 기존 값을 재사용하고 **새 토큰 캐시**를 확장함.
5. **캐시 블록 회수**: 참조가 끝난 블록을 반납해 **가용 메모리**를 복원함.

#### 한줄 요약
- **용량 산정•블록 할당•추가•회수** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **멀티 헤드 어텐션 캐시(Multi-Head Attention Cache, MHA Cache)**: 쿼리 헤드마다 독립 K•V를 저장하여 표현력은 높지만 캐시 용량이 크다.
- **그룹 쿼리 어텐션 캐시(Grouped-Query Attention Cache, GQA Cache)**: Q 그룹별로 K•V 헤드를 공유하여 캐시를 줄인다.
- **멀티 쿼리 어텐션 캐시(Multi-Query Attention Cache, MQA Cache)**: 모든 Q 헤드가 단일 K•V를 공유하여 캐시를 최소화한다.
- **양자화 키-값 캐시(Quantized Key-Value Cache, Quantized KV Cache)**: K•V를 낮은 비트로 저장하여 장문•고동시성의 메모리 사용을 추가로 줄인다.

</details>

- 표현력과 메모리 절감 수준에 따른 캐시 방식 구분

| 비교 기준 | MHA 캐시 | GQA•MQA 캐시 | 양자화 KV 캐시 |
|:---|:---|:---|:---|
| 적용 기준 | **표현력 우선** | **생성 메모리•대역폭 절감** | **장문•고동시성 추가 압축** |
| 핵심 특징 | 헤드별 **독립 키•값 저장** | 키•값 헤드의 **그룹•전체 공유** | 낮은 비트의 **키•값 표현** |
| 한계 | **최대 캐시 용량** | 공유에 따른 **품질 저하 가능** | **양자화 오차•변환 비용** |

#### 한줄 요약
- **헤드 공유•양자화 수준**으로 메모리와 품질 절충

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 단편화**: 빈 영역이 흩어져 새 요청의 연속 공간을 배정하기 어려운 현상이다.
- **페이징(Paging)**: 고정 크기 블록으로 캐시를 비연속 할당하여 단편화를 줄이는 방식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **오프로딩 지연**: GPU와 하위 메모리 계층 사이의 캐시 이동 때문에 토큰 생성이 늦어지는 현상이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장문•동시 요청의 **캐시 메모리 고갈** | **길이 상한•동적 수용 제어** | 메모리 부족 **방지** |
| 캐시 블록의 **단편화** | **고정 크기 페이징•빈 블록 회수** | 메모리 활용률 **향상** |
| 저정밀 캐시의 **정확도 저하** | **층•채널별 양자화•품질 회귀 시험** | 압축 품질 **검증** |
| GPU 캐시 부족의 **오프로딩 지연** | **대역폭 측정•재계산 비용 비교** | 지연 급증 **완화** |

#### 한줄 요약
- **압축 품질•오프로딩 지연** 동시 측정
