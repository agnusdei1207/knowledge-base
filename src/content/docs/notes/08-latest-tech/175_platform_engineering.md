## 미리 알고가기

- **플랫폼 엔지니어링(Platform Engineering)**: 인프라·배포·관측·보안 기능을 개발자용 내부 제품으로 제공하는 접근
- **DevOps**: 문화를 넘어 개발자 경험을 제품 관점으로 구현함
- **핵심 산출물**: IDP, golden path, 셀프서비스 자동화임



## Ⅰ. 개요

- 정의/개념: 내부 개발 플랫폼을 제품으로 제공하는 접근
- 기존 한계: 팀마다 도구를 직접 조합하고 인프라를 티켓으로 요청하면 개발자의 인지부하와 대기 시간이 커지고 운영 방식도 달라진다.

### 쉽게 이해하기 (학습용)

- 전담팀이 공용 설비를 내부 제품으로 운영하는 방식임

## Ⅱ. 특징

- 개발자 고객 관점이 플랫폼 로드맵을 정한다.
- golden path가 안전한 기본 경로를 제공한다.
- 추상화와 탈출 경로가 자율성을 함께 보장한다.
- 제품 지표가 플랫폼 효과를 지속 개선한다.

### 쉽게 이해하기 (학습용)

- 표준 조리법을 제공하고 실제 활용도를 지속 점검함

## Ⅲ. 아키텍처 및 구성요소

```text
관찰
  ↓
golden path
  ↓
IDP제공
  ↓
채택개선
```

| 설계 요소 | 설명 |
|:---|:---|
| 플랫폼 팀 | 제품 목표 및 수명주기 소유 |
| 개발자 경험 | 병목·인지부하 파악 |
| golden path | 권장 기술 흐름 조합 |
| IDP 계층 | 셀프서비스 소비 및 확인 |
| 제품 지표 | 데이터 기반 로드맵 개선 |

> 요약: 제품팀·권장 경로·IDP·지표를 제품으로 연결

### 쉽게 이해하기 (학습용)

- 공용 코스를 제품처럼 운영하며 채택 결과로 개선함

## Ⅳ. 원리 및 절차 흐름도

```text
여정관찰
    ↓
경로설계
    ↓
IDP제공
    ↓
채택 여부?
  ├─ 예: 기능확장
  └─ 아니요: 마찰개선
```

| 절차 | 설명 |
|:---|:---|
| 제품탐색 | 반복 병목 및 인지부하 관찰 |
| 우선순위 | 가치 및 위험도별 기능 선정 |
| 경로설계 | 안전한 기본값 설계 |
| 셀프서비스 | IDP를 통한 기능 노출 |
| 제품개선 | 채택 및 우회 근거로 수정 |


> 요약: 병목을 제품화하고 golden path로 채택을 유도함

### 쉽게 이해하기 (학습용)

- 표준 코스를 만들고 우회 근거를 조사해 메뉴를 개선함

## Ⅴ. 소프트웨어 운영 접근 비교

| 구분 | 플랫폼 엔지니어링 | DevOps | SRE |
|:---|:---|:---|:---|
| 적용 기준 | IDP·golden path | 자동화·문화 확산 | SLO·오류 예산 |
| 핵심 특징 | 내부 플랫폼 제품 제공 | 개발·운영 공동 책임 | 신뢰성 공학·운영 자동화 |
| 한계 | 강제 표준·플랫폼 비대화 | 역할·성과의 추상화 | 측정·당직·오류예산 부담 |


> 요약: 각자 역할로 상호 보완하는 관계임

### 쉽게 이해하기 (학습용)

- 각 담당 영역에 따라 안전과 효율을 나누어 운영함

## Ⅵ. 실무 사례

1. 기본값을 조합한 서비스 코스로 배포 시간을 측정함

### 쉽게 이해하기 (학습용)

- 기본값을 조합한 서비스 코스로 배포 시간을 측정함

## Ⅶ. 결론

- 개발자의 반복 작업과 인지 부하를 줄이기 위해 **공통 수요·골든 패스·셀프서비스·정책 자동화·채택률**을 검토하고, 내부 플랫폼을 제품으로 운영하는 플랫폼 엔지니어링을 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 사용 시간 단축 등 개발 경험 개선이 성공 기준임
