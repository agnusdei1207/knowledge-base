## 미리 알고가기

- **모델 드리프트(Model Drift)**: 데이터·개념·서빙 변화로 운영 모델의 성능이나 출력 특성이 기준선에서 이탈하는 포괄적 현상
- **발생 원인**: 원인은 Data Drift와 Concept Drift와 환경 변화와 서빙 설정 변화까지 다양함
- **관찰 지표**: 단순 정확도만 보지 말고 예측 분포와 calibration과 비즈니스 KPI를 함께 봐야 함


## Ⅰ. 개요

- 정의/개념: 모델 품질·출력이 기준선에서 이탈
- 기존 한계: 단일 정확도 지표만으로는 성능 이탈의 원인이 데이터·개념·서빙 환경 중 어디에 있는지 구분하기 어렵다.

### 쉽게 이해하기 (학습용)

- 같은 내비게이션도 도로가 바뀌거나 지도 파일과 설정이 잘못되면 안내 품질이 떨어지므로, 길 자체와 프로그램 설정 중 어디가 원인인지 나눠 봐야 함

## Ⅱ. 특징

- 데이터·개념·서빙 변화의 **복합 원인**
- 분포 경보와 정답 기반 **성능 영향 분리**
- 전체 평균과 부분 집단의 **구간별 오류 감시**

### 쉽게 이해하기 (학습용)

- 자동차 속도가 떨어졌다는 결과만으로 연료·도로·엔진 중 원인을 정할 수 없듯, 모델 품질 경보도 데이터와 설정을 따로 진단해야 함

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 성능 기준선 | 승인 시점 모델 버전별 품질·출력 지표 |
| 추론 관측 로그 | 입력·예측·지연·오류·버전 기록 |
| 정답 결합기 | 예측과 실제 정답을 동일 사건으로 연결 |
| 버전·설정 계보 | 아티팩트·코드·임계치 변경 이력 |
| 복구 정책 | 재학습·재보정·설정 복원 등 실행 조건 |

> 요약: 추론 기록으로 품질 이탈 확인 후 원인을 좁혀 복구함

### 쉽게 이해하기 (학습용)

- 출고 당시 성능표, 운행 기록, 나중에 확인한 고장 결과, 정비 이력을 함께 모아야 성능 저하와 원인을 연결할 수 있음

## Ⅳ. 원리 및 절차 흐름도

```text
기준 고정
   ↓
신호 수집
   ↓
정답 판정
   ↓
품질 비교
   ↓
원인 분해
   ↓
복구 검증
```

| 절차 | 설명 |
|:---|:---|
| 기준 고정 | 승인 품질과 모델·전처리 버전을 함께 등록함 |
| 신호 수집 | 입력·출력 분포와 지연·오류를 집계함 |
| 정답 판정 | 정답 유무에 따라 성능 저하 진단 범위를 결정함 |
| 품질 비교 | 전체·구간 성능과 확률 보정 오차를 비교함 |
| 원인 분해 | 데이터·개념·구성 원인에 따라 조치 선택함 |
| 복구 검증 | 이전 모델과 후보 모델 비교 후 승격함 |

> 요약: 정답으로 품질 저하 확인 후 원인별 복구 후보를 검증함

### 쉽게 이해하기 (학습용)

- 경고등만 켜졌을 때는 원인 후보를 조사하고, 실제 성능 저하가 확인되면 고장 부품 수리·설정 복원·차량 교체 중 맞는 조치를 검증하는 과정임

## Ⅴ. 모델 드리프트 원인 비교

| 구분 | 입력 데이터 | 개념 변화 | 구성 변화 |
| 적용 기준 | 운영 입력 변화 확인 | 정답 관계 변화 확인 | 서빙 환경 변경 확인 |
| 핵심 특징 | 입력 분포 기준선 이탈 | 예측 규칙 유효성 변화 | 전처리·버전·설정 변화 |
| 한계 | 성능 영향 별도 검증 | 라벨 지연 | 변경 이력 누락 위험 |
|:---|:---|:---|:---|
| 변화 위치 | 입력 분포·품질 | 입력-정답 관계 | 버전·전처리·임계치 |
| 주요 증거 | 피처 통계 | 정답 기반 오류 | 계보·설정 감사 |
| 우선 조치 | 원천 조사 | 재학습 | 설정 복원 |

> 요약: 원인별 변화를 분리한 뒤 복구 수단을 결정함

### 쉽게 이해하기 (학습용)

- 음식 맛이 달라졌을 때 재료, 조리법, 오븐 설정을 차례로 확인하듯 모델 품질 저하도 원인별로 다른 조치를 골라야 함

## Ⅵ. 실무 사례

1. 수요 예측 모델은 실제 판매량이 도착하면 예측 오차를 확인하고 데이터 원천 변경과 모델 버전을 대조함

### 쉽게 이해하기 (학습용)

- 판매량이나 심사 결과가 나온 뒤 예측과 맞춰 보고, 데이터가 바뀐 것인지 설정을 잘못 바꾼 것인지 찾아 각각 다른 복구를 적용함

## Ⅶ. 결론

- 모델 품질 저하에 정확히 대응하기 위해 **실제 정답·데이터·개념·모델 버전·서빙 설정**을 검토하고, 원인에 따라 수정·재학습·롤백을 선택한다

### 쉽게 이해하기 (학습용)

- 결과가 나빠졌다는 경보만으로 모델을 다시 만들지 말고, 실제 정답으로 문제를 확인한 뒤 재료·규칙·설정 중 잘못된 곳만 고쳐야 함
