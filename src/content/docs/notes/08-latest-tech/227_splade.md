## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SPLADE(SParse Lexical AnD Expansion Model)**: BERT의 마스크 언어 모델 헤드로 질의와 문서를 어휘 크기의 희소 벡터로 인코딩하고, 원문에 없는 연관 용어까지 가중치를 부여해 역색인에서 내적으로 순위를 계산하는 학습형 희소 검색 모델.
- **어휘 불일치(Vocabulary Mismatch)**: 질의와 문서가 같은 뜻을 다른 단어로 표현해 문자 일치 기반 검색이 관련 문서를 놓치는 현상.
- **역색인(Inverted Index)**: 용어별로 그 용어를 포함한 문서 목록과 가중치를 저장해 질의 용어만 조회하면 후보를 얻는 검색 자료구조.

</details>

- 정의/개념: 사전 학습 언어 모델이 각 용어의 중요도와 확장 용어를 학습해 산출하는 희소 벡터로 문서를 색인•검색하는 **SPLADE** 기반 신경망 희소 검색
- 배경/필요성: BM25는 **역색인** 조회 한 번으로 싸게 후보를 얻지만 단어가 다르면 회수가 끊기는 **어휘 불일치** 비용을 치르고, 밀집 임베딩은 의미는 잡지만 벡터 색인•근사 탐색 인프라와 해석 불가 비용을 치르므로, 역색인의 비용 구조를 그대로 유지한 채 확장 용어를 학습으로 끼워 넣어 두 비용을 동시에 줄일 중간 계층의 필요

#### 한줄 요약
- SPLADE는 밀집 검색의 의미 회수를 역색인 위에 얹는 선택이며, 벡터 DB 없이 기존 검색 엔진으로 어휘 불일치를 줄이려는 상황에서 BM25 교체 후보가 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **용어 확장(Term Expansion)**: 모델이 원문에 등장하지 않는 동의어•연관어에도 양의 가중치를 부여해 질의•문서 벡터를 어휘 공간에서 넓히는 동작.
- **용어 가중(Term Weighting)**: 문맥을 반영해 각 어휘 차원에 중요도를 부여하되 활성화가 없으면 0으로 두어 희소성을 유지하는 동작.
- **FLOPS 정규화(FLOPS Regularization)**: 역색인 조회 시 예상 부동소수점 연산량을 손실에 더해 벡터의 비영 차원 수를 억제하는 희소성 제약 항.

</details>

- 어휘 크기(약 3만 차원) 벡터에서 **용어 가중**과 **용어 확장**을 동시에 학습해 문맥적 중요도와 동의어 회수를 하나의 표현으로 처리
- 학습 시 **FLOPS 정규화**로 비영 차원 수를 억제해 역색인 포스팅 목록 길이와 검색 비용을 통제
- 벡터 각 차원이 실제 단어에 대응하므로 어떤 용어가 왜 점수에 기여했는지 사람이 읽을 수 있는 해석 가능성 보유
- 밀집 임베딩과 달리 근사 최근접 탐색 없이 기존 역색인 검색 엔진에 그대로 적재 가능

#### 한줄 요약
- 확장 용어를 많이 켤수록 회수는 오르지만 포스팅 목록이 길어져 조회 비용이 BM25보다 커지므로, FLOPS 정규화 강도가 회수와 지연 사이의 조절 손잡이가 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **마스크 언어 모델 헤드(Masked Language Model Head, MLM Head)**: BERT 사전 학습에서 가려진 토큰을 예측하기 위해 각 입력 위치마다 전체 어휘에 대한 로짓을 출력하는 선형•정규화 층.
- **로그 포화(Log Saturation)**: 각 어휘 로짓에 ReLU를 적용한 뒤 $\log(1+x)$로 눌러 특정 용어의 가중치가 과도하게 커지는 것을 막는 변환.
- **최대 풀링(Max Pooling)**: 입력 토큰 위치마다 나온 어휘 가중치 중 차원별 최댓값을 취해 문장 전체를 하나의 희소 벡터로 합치는 집계.

</details>

```text
SPLADE 검색기
|
+-- 인코더
|   +-- [BERT 인코더] -- 토큰별 문맥 표현
|   +-- [MLM 헤드] -- 위치별 어휘 로짓
|   +-- [로그 포화] -- ReLU 후 log(1+x)
|   `-- [최대 풀링] -- 어휘 크기 희소 벡터
|
+-- 색인
|   `-- [역색인] -- 용어별 (문서, 가중치) 포스팅
|
`-- 학습
    +-- [순위 손실] -- 정답•부정 문서 대비
    `-- [FLOPS 정규화] -- 비영 차원 억제
```

선의 의미: 가지는 포함, 가로선은 각 구성요소가 산출하는 결과

| 구성요소 | 책임 |
|:---|:---|
| BERT 인코더 | 토큰별 **문맥 표현** 산출 |
| MLM 헤드 | 위치마다 **전체 어휘 로짓** 출력으로 확장 용어 후보 생성 |
| 로그 포화•최대 풀링 | 로짓을 **희소 벡터** 하나로 집계 |
| 역색인 | 희소 벡터의 비영 차원을 **포스팅**으로 저장•조회 |
| 순위 손실•FLOPS 정규화 | **관련성**과 **희소성**을 동시에 학습 |

#### 한줄 요약
- 확장 용어의 원천은 별도 사전이 아니라 MLM 헤드가 사전 학습에서 이미 익힌 어휘 예측 분포이며, 그래서 추가 지식 베이스 없이 동의어 회수가 가능하다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **내적 점수(Dot Product Score)**: 질의 희소 벡터와 문서 희소 벡터에서 공통 비영 차원의 가중치 곱을 합산해 얻는 관련성 점수.
- **질의 인코딩 지연(Query Encoding Latency)**: 검색 시점마다 질의를 BERT에 통과시켜 희소 벡터를 만드는 데 드는 추가 시간.

</details>

```text
사용자 질의
      │
      ▼
1. 질의 인코딩 방식 판정
  ┌───────┴────────┐
[BERT 인코딩]    [원문 단어 가방]
  │                 │
  ▼                 ▼
확장•가중 질의    가중 없는 질의
  │                 │
  └───────┬─────────┘
          ▼
2. 역색인 포스팅 조회 (질의 비영 차원만)
          │
          ▼
3. 내적 점수 합산
          │
          ▼
4. 상위 k 문서 반환 → 재순위•RAG 생성기 입력
```

분기 결과: 질의까지 BERT로 인코딩하면 회수가 가장 높지만 검색마다 **질의 인코딩 지연**을 치르고, 문서만 인코딩하고 질의는 원문 단어 가방으로 두면 BM25 수준 지연으로 문서 측 확장 효과만 취한다

1. 질의 인코딩 방식 판정: 지연 예산에 따라 질의 측 확장 여부 결정
2. 역색인 포스팅 조회: 질의 비영 차원의 포스팅 목록만 순회
3. 내적 점수 합산: 공통 차원 가중치 곱의 합으로 **내적 점수** 산출
4. 상위 k 문서 반환: 재순위 모델 또는 RAG 생성기의 컨텍스트로 전달

#### 한줄 요약
- 문서 측 확장은 색인 시점에 한 번 치르는 비용이고 질의 측 확장은 검색마다 치르는 비용이므로, 지연 제약이 강한 서비스는 문서 측 확장만 켜는 것이 합리적이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **밀집 검색(Dense Retrieval)**: 질의와 문서를 수백 차원 실수 벡터로 인코딩하고 근사 최근접 탐색으로 유사 문서를 찾는 방식.
- **BM25(Best Matching 25)**: 단어 빈도•희귀도와 문서 길이를 반영해 어휘 일치 순위를 계산하는 확률적 검색 함수.

</details>

| 검색 방식 | SPLADE | BM25 | 밀집 검색 |
|:---|:---|:---|:---|
| 적용 기준 | 역색인 인프라 유지하며 **어휘 불일치** 완화 | 정확 용어•식별자 중심 검색 | 표현이 크게 다른 **의미 유사** 검색 |
| 핵심 특징 | 학습된 **용어 가중•확장** 희소 벡터 | 통계 기반 **용어 빈도** 가중 | 실수 **임베딩** 근사 탐색 |
| 한계 | 질의 인코딩 지연, 포스팅 길이 증가 | 동의어•다른 표현 **회수 누락** | 벡터 색인 비용, 점수 **해석 불가** |

#### 한줄 요약
- 세 방식의 차이는 "확장을 어디서 얼마나 치르는가"이며, BM25는 확장 없음, SPLADE는 어휘 공간 안에서 제한 확장, 밀집 검색은 연속 공간으로 완전 이동이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **하이브리드 검색(Hybrid Search)**: 희소•밀집 검색 후보를 점수나 순위로 결합해 한쪽의 누락을 다른 쪽이 메우는 방식.
- **지식 증류(Knowledge Distillation)**: 정밀하지만 느린 교차 인코더의 점수를 정답 신호로 삼아 검색 모델을 학습시키는 기법.
- **도메인 미세 조정(Domain Fine-tuning)**: 사내 문서•전문 용어로 모델을 재학습해 사전 학습 어휘 분포와 실제 코퍼스의 차이를 줄이는 작업.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 질의마다 BERT 인코딩으로 **지연 증가** | 문서 측만 확장하고 질의는 원문 단어 사용 | 검색 지연을 BM25 수준으로 유지 |
| 과도한 확장으로 **포스팅 길이 증가** | FLOPS 정규화 강도 상향, 상위 가중 차원만 색인 | 색인 크기•조회 비용 통제 |
| 전문 용어•신조어의 **어휘 분포 불일치** | **도메인 미세 조정**, **지식 증류**로 재학습 | 사내 코퍼스 회수율 향상 |
| 의미가 크게 벗어난 질의의 **회수 한계** | 밀집 검색과 **하이브리드 검색** 결합 | 어휘•의미 신호 상호 보완 |

#### 한줄 요약
- SPLADE 도입의 실제 판단점은 모델 정확도가 아니라 기존 역색인 엔진을 그대로 쓸 수 있느냐이며, 그 조건이 성립할 때만 밀집 검색 대비 인프라 비용 절감이 실현된다.

## Ⅶ. 결론

- 역색인 인프라를 유지한 채 회수를 높이려면 **SPLADE**, 정확 식별자만 필요하면 BM25, 표현 차이가 크면 밀집 검색 또는 하이브리드 선택

#### 한줄 요약
- SPLADE는 밀집 검색을 대체하기보다 BM25 자리를 대체하는 기술이며, RAG 검색기 설계에서 벡터 DB 없이 어휘 불일치를 줄여야 할 때 첫 번째로 검토할 선택지가 된다.
