## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **eBPF(Extended Berkeley Packet Filter)**: 검증된 프로그램을 커널 훅에 동적으로 부착해 네트워크•보안•관측 기능을 확장하는 실행 기술로 정의된다.
- **커널 훅(Kernel Hook)**: 네트워크•시스템 호출•추적 등 커널 실행 경로에서 프로그램을 연결하는 지점을 의미한다.

</details>

- 정의/개념: 검증된 프로그램을 커널 훅에서 실행하는 **eBPF**
- 배경/필요성: 커널 모듈은 결함이 **커널 전체 안정성**에 영향

#### 한줄 요약

- 검증된 프로그램을 커널 수정 없이 **동적 부착•실행**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **검증기(Verifier)**: eBPF 바이트코드의 종료 가능성과 메모리•포인터 안전성을 적재 전에 검사하는 커널 구성요소을 의미한다.
- **도움 함수(Helper Function)**: eBPF 프로그램이 지정된 실행 문맥에서 호출할 수 있도록 커널이 허용한 기능을 의미한다.
- **적시 컴파일(Just-In-Time, JIT)**: eBPF 바이트코드를 실행 시점에 기계어로 변환하는 방식로 정의된다.
- **eBPF 맵(eBPF Map)**: eBPF 프로그램과 사용자 공간이 상태와 통계를 공유하는 자료구조이다.

</details>

- **사전 안전성**: 적재 전 제어 흐름•메모리•포인터 안전성을 검증해 커널 실행 위험을 제한함.
- **고속 실행성**: 인터프리터 또는 **JIT** 네이티브 실행으로 커널 사건을 낮은 부하로 처리함.
- **제한 확장성**: 훅•프로그램 유형별 도움 함수와 문맥을 제한하고 **eBPF 맵**으로 커널•사용자 공간 상태 공유임.

#### 한줄 요약

- 아무 코드나 실행하는 것이 아니라 정해진 입구와 기능 안에서 검증된 코드만 빠르게 실행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사용자 공간 로더(User-Space Loader)**: eBPF 프로그램과 맵을 적재•부착하고 수명주기를 관리하는 개념을 의미한다.
- **검증기 안전성 검사**: 제어 흐름•메모리 접근•종료 가능성을 검사해 적재를 통제하는 활동을 의미한다.
- **eBPF 실행기**: 검증된 바이트코드를 해석하거나 JIT 코드를 실행하는 구성요소이다.
- **JIT 실행**: 검증된 바이트코드를 CPU 기계어로 변환하여 실행하는 개념로 정의된다.
- **커널 훅**: 네트워크•추적•보안 사건에 eBPF 프로그램을 연결하는 개념을 말한다.
- **도움 함수**: 실행 문맥에서 허용된 커널 기능만 호출하게 제한하는 함수이다.
- **중앙처리장치(Central Processing Unit, CPU)**: 명령 해석과 범용 연산을 수행하는 프로세서을 의미한다.

</details>

검증된 **eBPF** 바이트코드는 **JIT**을 거쳐 **CPU** 기계어로 실행되고 eBPF 맵과 상태를 공유한다.

```text
              [사용자 공간 로더]
                      |
                   [검증기]
                      |
               [eBPF 실행기]
                      |
         +------------+------------+
         |                         |
       [JIT]                    [커널 훅]
                                   |
                               [도움 함수]
                                   |
                               [eBPF 맵]
```

선의 의미: 사용자 공간 로더와 검증기가 eBPF 실행기의 적재 경계를 구성하고, 실행기는 JIT, 커널 훅, eBPF 맵과 결합되며 도움 함수가 커널 훅 문맥의 허용 기능을 제공한다.

| 구성요소 | 책임 |
|:---|:---|
| 사용자 공간 로더 | 프로그램 적재•부착•수명 주기 관리 |
| 검증기 | 종료•메모리•포인터•권한 안전성 검사 |
| eBPF 실행기 | 검증된 바이트코드 해석•실행 |
| JIT | 바이트코드의 CPU 기계어 변환 |
| 커널 훅 | 커널 사건의 실행 문맥 제공 |
| 도움 함수 | 허용된 커널 기능 호출 |
| eBPF 맵 | 정책•상태•통계의 공유•영속 |

#### 한줄 요약

- 사용자가 프로그램을 제출하면 검증기를 거쳐 지정된 커널 훅에 부착되고 결과는 eBPF 맵에 기록된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **바이트코드 적재**: 사용자 공간 로더가 eBPF 프로그램을 커널 검증기에 제출하는 절차을 말한다.
- **훅 부착**: 검증된 프로그램을 네트워크•추적•보안 사건이 발생하는 지점에 연결하는 동작을 말한다.

</details>

```text
사용자 공간 로더 ── 프로그램 적재 요청 ──▶ 검증기
검증기
   │ 1. 바이트코드 안전성 검사
   └── 검증된 바이트코드 ──▶ eBPF 실행기•JIT
사용자 공간 로더 ── 2. 프로그램 훅 부착 ──▶ 커널 훅•Helper
커널 훅•Helper ── 3. 커널 이벤트 실행 ──▶ eBPF 실행기•JIT
eBPF 실행기•JIT ── 4. 정책 조회•상태 기록 ──▶ eBPF Map
```

### 동작 원리

1. **바이트코드 안전성 검사**: 종료•메모리•포인터 규칙 검사
2. **프로그램 훅 부착**: 네트워크•추적•보안 지점에 연결
3. **커널 이벤트 실행**: **eBPF 실행기•JIT**가 허용 문맥에서 실행
4. **정책 조회•상태 기록**: **eBPF 맵**의 정책 조회•통계 갱신

#### 한줄 요약

- 로드 시 검증기가 안전성을 확인하고 이벤트 발생 시마다 부착된 프로그램을 실행해 결과를 맵에 기록한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **커널 모듈**: 운영체제 커널 권한으로 직접 적재되어 깊은 기능 변경을 수행하는 코드이다.
- **사용자 공간 에이전트**: 독립 프로세스에서 시스템 응용 프로그래밍 인터페이스를 이용해 상태를 관측하고 제어하는 프로그램이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 소프트웨어 기능과 데이터를 호출하기 위한 명세화된 접점을 의미한다.

</details>

| 커널 기능 확장 방식 | eBPF | 커널 모듈 | 사용자 공간 에이전트 |
|:---|:---|:---|:---|
| 적용 기준 | 빠른 **동적 정책•관측** | 깊은 **커널 기능 변경** | 강한 **격리•개발 편의** |
| 핵심 특징 | **eBPF** 검증 후 **커널 훅**에서 실행 | **커널 코드**로 직접 적재 | 프로세스에서 **시스템 API** 사용 |
| 한계 | **검증•훅•Helper•권한** 제약 | 결함의 **커널 전체 영향** | **문맥 전환•데이터 복사** 비용 |

#### 한줄 요약

- eBPF는 검증된 현장 작업자, 커널 모듈은 내부 구조 변경, 에이전트는 외부 관찰자에 가깝다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **한 번 컴파일 후 어디서나 실행(Compile Once, Run Everywhere, CO-RE)**: 한 번 컴파일한 eBPF 프로그램을 여러 커널 구조에 맞추는 방식로 정의된다.
- **버클리 타입 형식(BPF Type Format, BTF)**: 커널 자료형과 구조체 배치 정보를 제공하는 메타데이터 형식을 의미한다.
- **핀 객체**: 프로그램 종료 뒤에도 유지하고 접근 권한을 관리하도록 가상 파일 시스템 경로에 고정한 eBPF 객체을 의미한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 커널 버전별 **타입•기능 차이** | **CO-RE•BTF•기능 탐지** 적용 | **이식성•배포 성공률** 향상 |
| 고빈도 훅의 **실행 오버헤드** | **명령•Map 접근 최소화**와 벤치마크 | **커널 경로 지연** 억제 |
| 적재 권한 탈취•정책 변조 | **최소 권한•서명•핀 객체** 접근 통제 | **커널 공격 표면** 축소 |

#### 한줄 요약

- Cilium 정책 프로그램은 대상 커널 기능을 먼저 확인하고 패킷당 처리량과 Map 경합을 부하 시험한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **커널 호환성**: 대상 커널이 프로그램 유형•훅•도움 함수•버클리 타입 형식 정보를 지원하는 정도을 의미한다.
- **최소 권한**: 프로그램 적재•부착•맵 접근에 필요한 권한만 주는 보안 원칙을 말한다.

</details>

- 동적 정책•관측은 **eBPF**, 깊은 기능 변경은 **커널 모듈** 선택

#### 한줄 요약

- **호환성 검증•최소 권한•객체 회수**를 갖춘 eBPF만 배포
