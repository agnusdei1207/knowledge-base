## 미리 알고가기

- **확장 버클리 패킷 필터**: 커널 훅에서 검증 프로그램을 실행함
- **네트워킹**: 네트워킹·보안·관측 등 확장성을 제공함
- **커널 모듈보다 안전성**: 검증 가능한 프로그램 제약으로 안전성 확보함



## Ⅰ. 개요

- **정의/개념**: 검증 프로그램을 커널 후크에서 실행
- **배경/필요성**: 커널 모듈 없이 안전한 기능 확장

### 쉽게 이해하기 (학습용)

- 커널을 바꾸지 않고 검증된 작업 지시서를 이벤트 지점에 붙이는 방식이다.

## Ⅱ. 특징

- 검증기가 흐름·메모리·포인터 안전성을 검사한다
- JIT가 검증 바이트코드를 기계어로 바꾼다
- 프로그램 유형별 후크·허용 함수가 다르다
- 맵이 커널·사용자 공간의 상태를 공유한다
- 적재·부착 권한 제한이 공격 표면을 줄인다

### 쉽게 이해하기 (학습용)

- 검증된 프로그램만 허용된 후크와 함수를 쓰고 맵으로 상태를 나눈다.

## Ⅲ. 아키텍처 및 구성요소

```text
[제어기] → [검증기] → [실행기] → [후크]
    ↕                         ↕
   [맵] ←──── 상태·통계 ─────┘
```

| 설계 요소 | 설명 |
|:---|:---|
| 프로그램 | 바이트코드·맵·후크 정보 |
| 검증기 | 흐름·메모리 안전성 검사 |
| 실행기 | 해석 또는 JIT 기계어 실행 |
| 후크·함수 | 실행 문맥·허용 기능 제한 |
| 맵 | 정책·상태·통계 공유 |
| 제어기 | 객체 생성·부착·수명 관리 |

> 요약: 제어기가 검증된 프로그램을 후크에 붙여 실행한다

### 쉽게 이해하기 (학습용)

- 관리자가 낸 지시서를 검증한 뒤 후크에 붙이고 결과는 맵으로 돌려준다.

## Ⅳ. 원리 및 절차 흐름도

```text
컴파일
    ↓
권한확인
    ↓
검증실행
    ↓
후크부착
    ↓
맵정리
```

| 절차 | 설명 |
|:---|:---|
| 프로그램 컴파일 | 바이트코드·객체 생성 |
| 권한·기능 확인 | 후크·함수·권한 확인 |
| 검증·실행 준비 | 검증 뒤 해석·JIT 준비 |
| 후크 부착·실행 | 이벤트 문맥에서 프로그램 실행 |
| 맵 수집·해제 | 상태 수집·객체 수명 정리 |

> 요약: 기능·권한을 확인하고 검증된 프로그램만 부착한다

### 쉽게 이해하기 (학습용)

- 기능과 권한을 확인한 뒤 검증·부착하고 맵과 객체 수명을 정리한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | eBPF | 커널 모듈 | 사용자 공간 에이전트 |
|:---|:---|:---|:---|
| 실행 위치 | 지정 커널 후크 | 커널 코드 직접 적재 | 사용자 프로세스 |
| 안전 경계 | 검증기·유형·권한 | 높은 권한·넓은 영향 | 프로세스·운영체제 격리 |
| 선택 조건 | 빠른 동적 정책·관측 | 깊은 커널 기능 | 단순 개발·강한 격리 |

> 요약: 실행 위치·검증 경계·확장 깊이로 방식을 고른다

### 쉽게 이해하기 (학습용)

- eBPF는 검증된 내부 지시서, 모듈은 개조, 에이전트는 외부 감독이다.

## Ⅵ. 실무 사례

1. Cilium은 eBPF로 정책·흐름을 처리한다
2. 관측 도구는 후크 이벤트를 링 버퍼로 보낸다

### 쉽게 이해하기 (학습용)

- Cilium은 패킷 후크와 맵으로 서비스·보안 정책을 처리한다.
- 관측 도구는 함수·시스템 호출 사건을 사용자 공간에 전달한다.

## Ⅶ. 결론

- 검증·후크 문맥·권한·객체 수명을 함께 설계한다.

### 쉽게 이해하기 (학습용)

- 검증기만 믿지 말고 설치 권한과 후크·맵 수명도 관리해야 한다.
