## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜 프롬프트(Model Context Protocol Prompt, MCP Prompt)**: 서버가 제공한 작업 양식에 사용자가 값을 채우고 검토한 뒤 모델에 전달하는 재사용 기능을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 애플리케이션과 외부 서버가 컨텍스트와 기능을 교환하는 표준 프로토콜이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 정의: 서버 양식을 사용자가 선택•검토하는 **MCP Prompt**이다.
- 배경/필요성: 앱별 지시문은 작업 양식의 공유•재사용과 사용자 통제가 어려움.

#### 한줄 요약

- 사용자가 **작업 양식•인자**를 검토한 뒤 모델 전달

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사용자 제어(User-controlled)**: 프롬프트 선택과 모델 전달 여부를 사용자가 결정하는 제어 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **프롬프트 메시지(PromptMessage)**: 역할과 텍스트•이미지•내장 리소스 등의 콘텐츠를 묶은 메시지로 정의된다.
- **내장 리소스(Embedded Resource)**: 프롬프트 메시지 안에 직접 포함된 문서나 코드 같은 컨텍스트를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- **사용자 제어**: 템플릿 선택•모델 전달 여부 결정
- **생성 축**: 인자값으로 역할별 메시지 생성
- **프롬프트 메시지**: 역할•텍스트•이미지•리소스 구성

#### 한줄 요약

- 서버는 메시지 생성, 사용자는 **전달 여부 결정**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **프롬프트 기술자(Prompt Descriptor)**: 템플릿의 이름•설명과 입력할 인자 목록을 제공하는 구성요소를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **인자 정의(Argument Definition)**: 템플릿에 채울 값의 이름•설명•필수 여부를 정한 계약이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **콘텐츠 블록(Content Block)**: 프롬프트 메시지 안에서 텍스트•이미지•리소스를 구분해 담는 단위로 정의된다.
- **사용자 인터페이스(User Interface, UI)**: 사용자가 프롬프트를 탐색•입력•검토하는 클라이언트 화면을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- **기술자•인자 정의•콘텐츠 블록•UI**로 양식 구성

```text
                       [클라이언트 UI]
                         /           \
               [프롬프트 기술자]---[프롬프트 메시지]
                        |
                    [인자 정의]
```

선의 의미: 클라이언트 UI는 프롬프트 기술자의 명세와 완성된 프롬프트 메시지를 사용자에게 제공하고, 인자 정의는 프롬프트 기술자의 입력 계약에 속함.

| 구성요소 | 책임 |
|:---|:---|
| 프롬프트 기술자 | **프롬프트 기술자**가 이름•설명과 인자 목록을 제공함 |
| 인자 정의 | **인자 정의**로 인자명•설명•필수 여부를 명시함 |
| 프롬프트 메시지 | **프롬프트 메시지**가 **콘텐츠 블록**을 구성함 |
| 클라이언트 UI | **UI**가 탐색•입력•검토•전달을 지원함 |

#### 한줄 요약

- 서버는 **양식•인자 정의**, 클라이언트는 선택•검토

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **프롬프트 목록(prompts/list)**: 서버가 제공하는 프롬프트의 이름•설명•인자를 조회하는 요청을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **프롬프트 조회(prompts/get)**: 프롬프트 이름과 인자를 보내 완성된 메시지를 받는 요청으로 정의된다.
- **모델 문맥(Model Context)**: 모델이 응답을 생성할 때 함께 참고하는 지시와 입력 정보로 정의된다.
- **MCP Client(Model Context Protocol Client)**: 프롬프트 목록•메시지를 서버에 요청하는 주체를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **MCP Server(Model Context Protocol Server)**: 프롬프트 계약과 완성 메시지를 제공하는 주체로 정의된다.
- **프롬프트 목록 조회(Prompt List Request)**: prompts/list로 사용 가능한 템플릿 계약을 확인하는 단계를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **완성 메시지 조회(Completed Message Request)**: prompts/get으로 인자가 반영된 역할별 메시지를 생성하는 단계를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **승인한 메시지 전달(Approved Message Delivery)**: 사용자가 검토한 메시지만 모델 문맥에 반영하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **MCP Client•Server**가 목록•완성 메시지 교환

```text
MCP 클라이언트
   │ 1. 프롬프트 목록 조회
   ▼
MCP 서버
   │ 프롬프트 이름•설명•인자 반환
   ▼
MCP 클라이언트
   │ 목록 제공
   ▼
사용자
   │ 템플릿 선택•인자 입력
   ▼
MCP 클라이언트
   │ 2. 완성 메시지 조회
   ▼
MCP 서버
   │ 역할별 프롬프트 메시지 반환
   ▼
MCP 클라이언트
   │ 완성 메시지 검토 요청
   ▼
사용자
   │ 승인한 메시지 전달 요청
   ▼
MCP 클라이언트
   │ 3. 승인한 메시지 전달
   ▼
모델
   │ 모델 생성 결과 반환
   ▼
MCP 클라이언트
   │ 작업 결과 제공
   ▼
사용자
```

### 동작 원리

1. 프롬프트 목록 조회: **prompts/list**로 사용 가능한 템플릿 계약을 확인함.
2. 완성 메시지 조회: **prompts/get**으로 인자가 반영된 메시지를 생성함.
3. 승인한 메시지 전달: 검토된 메시지만 **모델 문맥**에 반영함.

#### 한줄 요약

- **목록•완성 메시지 조회** 후 승인 메시지만 전달

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Resource**: 애플리케이션이 제공하고 모델이 문맥으로 읽는 데이터를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **Tool**: 모델이 구조화된 인자로 호출해 외부 행동을 수행하는 기능이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **Prompt**: 사용자가 선택해 작업 메시지와 입력 틀을 만드는 기능을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **MCP Resource(Model Context Protocol Resource)**: MCP에서 문맥 데이터를 제공하는 기능으로 정의된다.
- **URI(Uniform Resource Identifier)**: 리소스를 식별하고 조회하는 주소이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **Resource•Tool•Prompt**를 문맥•행동•작업 지시로 구분

| MCP 기능 | Resource | Tool | Prompt |
|:---|:---|:---|:---|
| 적용 기준 | **Resource**는 문맥 데이터를 제공함 | **Tool**은 외부 기능을 실행함 | **Prompt**는 작업 지시 틀을 제공함 |
| 핵심 특징 | 앱 제어•**URI** 조회를 수행함 | 모델 제어•스키마를 호출함 | 사용자 제어•메시지를 생성함 |
| 한계 | 직접 행동 수행 불가임 | 부작용•권한 위험이 존재함 | 사용자 선택•입력이 필요함 |

> 요약: 문맥에는 **Resource**, 행동에는 **Tool**, 작업 지시에는 **Prompt**를 적용함.

#### 한줄 요약

- 문맥은 **Resource**, 행동은 **Tool**, 작업 틀은 Prompt

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **악성 지시(Malicious Instruction)**: 사용자의 의도와 달리 모델 행동을 바꾸려고 템플릿에 숨겨 넣은 명령을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **마스킹(Masking)**: 비밀정보의 일부나 전부를 가려 노출을 제한하는 처리를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **작업 재현성(Task Reproducibility)**: 같은 템플릿과 입력에서 일관된 작업 결과를 다시 얻을 수 있는 성질로 정의된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서버 템플릿의 **악성 지시** 혼입 | 출처 표시와 전달 전 전체 검토를 수행함 | 비신뢰 지시의 모델 문맥 유입을 차단함 |
| 인자에 비밀정보를 넣는 정보 노출 | 인자별 민감도•**마스킹**•입력을 제한함 | 템플릿 재사용 중 최소 정보 공개를 달성함 |
| 템플릿 변경에 따른 결과 비일관성 | 버전•변경 이력•승인본을 고정함 | 여러 클라이언트의 **작업 재현성**을 확보함 |

#### 한줄 요약

- **작업 재현성**을 위해 출처•버전•민감 인자 관리

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **사용자 검토(User Review)**: 완성된 메시지의 출처와 인자값을 사람이 확인한 뒤 모델 전달을 승인하는 통제로 정의된다.

</details>

- 반복 작업 지시 공유는 **MCP Prompt•사용자 검토** 적용

#### 한줄 요약

- **반복성•민감 인자**에 따라 Prompt 사용과 검토 결정
