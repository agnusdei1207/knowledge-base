## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **온톨로지(Ontology)**: 도메인의 개념•관계•제약•공리를 공식화한 의미 모형이다.

</details>

- 정의: 도메인의 개념•관계•제약•공리를 명시한 **온톨로지**이다.
- 배경/필요성: 시스템별 **용어•관계 해석 차이** 기반 지식 통합 곤란

#### 한줄 요약

- 여러 시스템의 용어•관계 해석을 통일하는 **공유 설계도** ## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **개념 계층(Concept Hierarchy)**: 상위•하위 개념과 상속 관계를 정의한다.
- **공리(Axiom)**: 암묵 지식 추론과 모순 판정에 사용하는 논리 규칙이다.

</details>

- 클래스의 상하위•상속 관계를 정하는 **개념 계층**
- 속성의 정의역•치역•카디널리티를 밝히는 **의미 제약**
- 공리로 암묵 지식•모순을 판정하는 **논리 추론** #### 한줄 요약

- **개념 계층•의미 제약•공리** 기반 분류와 모순 판정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **객체 속성(Object Property)**: 개체와 개체의 관계를 정의한다.
- **데이터 속성(Data Property)**: 개체와 리터럴 값의 관계를 정의한다.
- **클래스(Class)**: 공통 성질과 제약을 공유하는 도메인 개념 집합이다.
- **개체(Individual)**: 특정 클래스에 속하는 실제 대상이나 사례이다.
- **공리 적용**: 클래스•속성의 포함•동치•배타•제약 선언이다.
- **정의역•치역•카디널리티**: 속성 대상•결과•허용 개수를 제한한다.

</details>

```text
                         [공리•제약 저장소]
                       /          |          \
          [클래스 저장소] ----- [개체 저장소] ----- [데이터 속성 저장소]
                    \              /
                    [객체 속성 저장소]
```

선의 의미: 공리•제약이 클래스•개체•속성의 허용 관계를 규정한다.

| 구성요소 | 책임 |
|:---|:---|
| 클래스 저장소 | **도메인 개념•상하위 계층** 정의 |
| 개체 저장소 | 클래스별 **실제 대상•식별자** 관리 |
| 객체 속성 저장소 | **개체 간 관계** 정의 |
| 데이터 속성 저장소 | **개체•리터럴 값 관계** 정의 |
| 공리•제약 저장소 | **분류 추론•모순 판정 규칙** 관리 |

#### 한줄 요약

- **클래스•개체•속성•공리•제약** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **추론기(Reasoner)**: 명시적 사실과 공리로 분류•파생 사실•모순을 계산한다.
- **일관성 검사(Consistency Check)**: 개념•관계•규칙의 논리 모순을 탐지한다.

</details>

```text
온톨로지 지식베이스
   │ 1. 클래스 계층•관계 범위
   │ 2. 정의역•치역•카디널리티
   │ 3. 검증 제약•개체 매핑 규칙
   │ 4. 개체•속성 사실
   ▼
추론기
   │ 5. 공리 기반 추론•일관성 검사
   └── 분류 결과•모순 판정 ──▶ 온톨로지 지식베이스
```

### 동작 원리

1. 클래스 계층•관계 범위: 합의한 개념의 상하위 구조와 관계 대상을 정의함.
2. 정의역•치역•카디널리티: 속성에 허용할 클래스와 개수 제한을 명시함.
3. 검증 제약•개체 매핑 규칙: 원천 데이터를 온톨로지 개념에 연결함.
4. 개체•속성 사실: 추론기가 판정할 명시적 사실을 제공함.
5. 공리 기반 추론•일관성 검사: 파생 분류와 논리적 모순을 판정함.

#### 한줄 요약

- **계층•제약•매핑•사실•공리 추론** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **분류체계(Taxonomy)**: 용어의 상하위 분류 관계를 정의한다.
- **온톨로지**: 개념•관계•제약•공리를 정의한다.
- **지식그래프(Knowledge Graph)**: 개체•관계•사실을 그래프로 관리한다.

</details>

| 구분 | 분류체계 | 온톨로지 | 지식그래프 |
|:---|:---|:---|:---|
| 적용 기준 | **분류 계층** 필요 | 공유 의미•**추론** 필요 | **경로 탐색** 중심 |
| 핵심 특징 | 용어•**상하위 관계** | **개념•제약•공리** | **개체•관계•사실** |
| 한계 | 관계•**추론 표현 제한** | 합의•**추론 비용** | 개체 연결•**정합성 비용** |

#### 한줄 요약

- **분류 계층•의미 추론•경로 탐색** 대상 따라 모델 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **웹 온톨로지 언어(Web Ontology Language, OWL)**: 온톨로지 표현과 추론을 위한 표준 언어이다.
- **OWL 프로파일(OWL Profile)**: 표현력과 추론 복잡도를 제한한 OWL 부분집합이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동음이의어와 **분류 기준 충돌** | 용어집•상하위 관계의 **공동 검토** | 공유 개념의 **해석 일관성** 확보 |
| 규칙의 **공리 복잡도 증가** | **OWL 프로파일** 선택•규칙 복잡도 제한 | **결정 가능성•응답 시간** 확보 |
| 변경으로 **하위 호환성 훼손** | 식별자•버전•폐기 매핑과 **일관성 회귀 검사** | 기존 개체•질의의 **호환성** 보존 |

#### 한줄 요약

- **용어 합의•추론 복잡도•하위 호환성** 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **하위 호환성(Backward Compatibility)**: 변경 후에도 기존 개체•질의가 같은 의미로 동작하는 성질이다.

</details>

- 용어 계층만 필요하면 **분류체계**, 의미 제약•추론은 **온톨로지** 선택

#### 한줄 요약

- **분류 깊이•추론 필요성** 대상 따라 의미 모델 결정
