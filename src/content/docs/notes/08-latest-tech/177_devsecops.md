## 미리 알고가기

- **개발보안운영(Development, Security and Operations, DevSecOps)**: 개발·보안·운영이 보안 책임과 자동 검증을 수명주기에 내재화하는 방식
- **보안팀**: 도구 도입이 아닌 파이프라인 보안 내재화 핵심
- **핵심**: Shift left, 정책 코딩, 지속적인 검증 수행



## Ⅰ. 개요

DevSecOps는 개발·보안·운영이 소프트웨어 개발 수명주기(Software Development Life Cycle, SDLC)의 각 단계에서 보안 결과를 공동 소유하고 자동 검증과 위험 기반 의사결정, 운영 피드백을 지속 전달하는 문화·프로세스·기술 체계임

- 정의/개념: 개발·운영 전 과정에 보안을 내재화한 방식
- **배경/필요성**: 릴리스 직전 수동 보안 심사만으로 빠른 배포와 공급망 변경의 취약점 조기 차단 곤란

### 쉽게 이해하기 (학습용)
- 개발·사용 단계마다 담당자가 안전을 확인하는 방식

## Ⅱ. 특징

- 전 단계 보안 활동이 결함 노출 시간을 줄인다.
- Shift Left·Right가 예방과 탐지를 연결한다.
- 위험 기반 게이트가 차단·예외를 차등화한다.
- SBOM·서명이 공급망 무결성을 입증한다.

### 쉽게 이해하기 (학습용)
- 위험 우선순위를 정해 중요한 결함부터 처리하는 방식

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 보안 요구 | 보호 자산 및 위협, 위험 정의 |
| 개발 피드백 | 분석 결과 및 수정 문맥 제공 |
| 정책 게이트 | 영향도 기반 차단 및 승인 |
| 공급망 증거 | SBOM 등 출처 및 무결성 추적 |
| 운영 환류 | 사고 탐지 및 정책 개선 반영 |

> 요약: 위협 모델·위험 게이트·운영 피드백을 연결

### 쉽게 이해하기 (학습용)

- 무엇을 지킬지 먼저 정하고 부품표와 검사 기록을 남긴 뒤 실제 사용 중 발견한 문제를 다음 설계에 반영해야 함

## Ⅳ. 원리 및 절차 흐름도

```text
모델링
 ↓
코드검사
 ↓
빌드게이트
 ↓
배포승인
 ↓
운영환류
```

| 절차 | 설명 |
|:---|:---|
| 보안 모델링 | 자산·위협 및 위험 수준 정의함 |
| 코드 검사 | 취약점 확인 후 수정안 제공함 |
| 빌드 게이트 | SBOM 생성 및 정책 검증함 |
| 배포 승인 | 무결성 확인 후 배포함 |
| 운영 환류 | 사고 탐지 및 보안 정책 갱신함 |

> 요약: 개발 피드백·위험 게이트·운영 탐지를 연결

### 쉽게 이해하기 (학습용)

- 개발 중에는 빨리 알려 고치게 하고 출고 때는 위험을 판정하며 사용 중 새 문제가 나오면 부품표로 영향을 찾아 다시 고침

## Ⅴ. 소프트웨어 보안 적용 방식 비교

| 구분 | DevSecOps | 파이프라인 보안 | 보안 심사 |
|:---|:---|:---|:---|
| 적용 기준 | 위험 기반 의사결정 | 규칙 자동 설정 | 전문가 수동 심사 |
| 핵심 특징 | 수명주기 공동 보안 책임 | CI/CD 자동 보안 게이트 | 릴리스 시점 전문가 검토 |
| 한계 | 도구 경보·책임 분산 | 설계·운영 위험 사각지대 | 늦은 발견·출시 지연 |

> 요약: 전 수명주기 위험 관리와 운영 환류를 통합

### 쉽게 이해하기 (학습용)

- 검사 기계를 늘리는 것만으로는 부족하고 어느 결함을 왜 막고 누가 언제 고칠지 전 과정의 규칙이 있어야 함

## Ⅵ. 실무 사례

1. **인터넷 결제 API의 위험 기반 릴리스**에서 SAST·비밀 탐지 후 고위험 결함의 병합 차단

### 쉽게 이해하기 (학습용)

- 인터넷 결제 API의 위험 기반 릴리스

## Ⅶ. 결론
- 개발 전 과정의 보안 내재화를 위해 위험 기반 게이트·운영 환류를 검토하여 **DevSecOps** 활용

### 쉽게 이해하기 (학습용)

- 보안을 개발 속도의 반대편에 두지 않고 중요한 위험을 더 일찍 정확하게 알려 안전한 변경을 빠르게 만드는 것이 목표임
