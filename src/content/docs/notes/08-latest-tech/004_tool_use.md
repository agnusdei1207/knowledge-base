## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **도구 호출(Tool Use)**: LLM이 외부 기능·인자를 제안하고, 호스트가 검증·승인·실행 후 결과를 반환하는 연계 방식. 모델과 외부 시스템 간 신뢰 경계(Trust Boundary)를 설정하여 안전한 자원 접근을 보장하는 아키텍처.
- **대규모 언어 모델(Large Language Model, LLM)**: 목표 해석 기반 외부 기능·인자 제안 엔진. 추론 불가능한 실시간 조회·변경 업무를 외부 기능에 위임하는 호출 제안자(Caller).

</details>

- 개념: LLM 제안과 호스트 검증•실행을 분리하는 **도구 호출**
- 배경/필요성: 언어 모델 자체는 외부 데이터베이스 조회, 파일 시스템 조작, 실시간 웹 검색, API 연동 등 실제 환경과 상호작용하는 능력이 결여되어 있어 단순 텍스트 생성기에 머무르는 근본적 한계가 존재하고, 모델의 비신뢰 출력이 외부 시스템에 직접 접근할 경우 시스템 보안 침해 위험이 발생함에 따라, 모델이 정형화된 JSON 스키마로 도구와 인자를 제안(Proposal)하고 호스트가 이를 엄격히 검증·승인·실행한 뒤 결과를 정규화해 반환하는 도구 호출(Tool Use) 신뢰 경계(Trust Boundary) 아키텍처를 구축하여 **LLM의 기능적 확장(인터넷 검색, 코드 실행, DB 연동), 외부 시스템과의 안전한 인터페이스 격리 및 모델-호스트 간 명확한 책임 분리 기반의 엔터프라이즈 연계**를 달성할 필요

#### 한줄 요약
- 모델의 **도구•인자 제안**과 호스트의 실행을 갈라 두면 오판이 곧바로 부작용이 되지 않지만, 그만큼 인자 검증과 권한 판단 책임이 호스트로 옮겨 온다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **실행 책임 분리(Separation of Execution Responsibility)**: 모델은 제안, 호스트는 권한 확인·실행을 담당하여 오류의 시스템 침해 방지.
- **JSON 스키마(JSON Schema)**: 도구 인자의 자료형·필수 필드·허용 범위를 구조적으로 검증하여 실행 실패·오류 차단.
- **책임 축(Responsibility Axis)**: 모델의 호출 제안과 호스트의 확인·실행 책임을 분리하여 소재 추적성 확보.
- **검증 축(Validation Axis)**: 인자·권한·업무 규칙을 다층 검증하여 비인가 행위 방지.
- **결과 축(Result Axis)**: 도구 출력·오류를 비신뢰 관찰값으로 정규화하여 정책 우회 방지.

</details>

- **책임 축**: 모델 제안과 호스트 실행 책임 분리
- **검증 축**: 스키마•권한•업무 규칙 다층 검증
- **결과 축**: 외부 출력을 비신뢰 관찰값으로 정규화

#### 한줄 요약
- **책임 분리•다층 검증** 기반 외부 기능 호출

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 애플리케이션과 외부 데이터•도구의 연결 및 메시지 교환을 표준화한 프로토콜을 뜻하며, 도구 명세의 등록과 조회를 위한 공통 인터페이스를 제공하여 다양한 도구를 일관된 방식으로 통합하는 필수적인 역할을 수행한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 실행 중개기가 외부 기능을 정해진 요청•응답 규격으로 호출하기 위한 표준 인터페이스이며, 내부 도구 호출 체계를 외부 시스템과 연결하는 기술적 기반이 된다.
- **인간 참여형 통제(Human-in-the-Loop, HITL)**: 고위험 도구 실행 전에 사람이 맥락과 영향을 검토하고 승인하는 통제 기법을 의미하며, 자동화된 실행에서 발생할 수 있는 비가역적 업무 영향을 사람이 사전에 차단할 수 있게 하는 핵심 아키텍처 요소이다.

</details>

```text
                [도구 레지스트리]
                         |
                    [모델•라우터]
                         |
                    [실행 중개기]
                         |
                    [결과 처리기]
```

선의 의미: 도구 레지스트리의 명세를 모델•라우터가 참조하고, 실행 중개기의 신뢰 경계를 거쳐 결과 처리기에 연결되는 도구 호출 구조를 나타냄.

| 구성요소 | 주요 책임 |
|:---|:---|
| 도구 레지스트리 | MCP·API 스키마와 **위험·권한 범위** 제공 |
| 모델·라우터 | JSON 스키마 기반 **인자·호출 후보** 생성 |
| 실행 중개기 | 인증·스키마·**HITL·샌드박스** 실행 |
| 결과 처리기 | 외부 결과를 **비신뢰 관찰값**으로 정규화 |

#### 한줄 요약
- **레지스트리•실행 중개기** 기반 결과 정규화

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **도구 결과(Tool Result)**: 외부 실행이 반환한 데이터나 오류를 다음 판단에 사용하도록 구조화한 비신뢰 관찰값을 말하며, 신뢰 경계 밖의 입력임을 표시하여 모델이 외부 출력을 내부 명령과 동일하게 취급하지 않도록 하는 주요 기전으로 작용한다.
- **도구명•스키마•위험 정보 제공(Tool/Schema Provision)**: 모델에 허용 기능 목록•인자 제약 조건•부작용 가능성을 알리는 초기 단계이며, 모델이 호출 가능 범위를 사전에 인지하도록 하는 기술적 기반이 된다.
- **선택 도구•구조화 인자 제안(Tool/Argument Proposal)**: 사용자 목표에 맞는 호출 후보와 인자를 생성하는 단계이며, 자유 텍스트가 아닌 구조화 형식으로 출력을 제한하여 호출 의도를 명확히 하는 기술적 기반이 된다.
- **검증•승인된 호출 실행(Verified Execution)**: 값•대상•권한•업무 규칙을 확인해 제한된 샌드박스 환경에서 실행하는 단계를 지칭하며, 다단계 확인을 통해 비인가 실행을 차단한다.
- **실행 결과•오류 반환(Execution Return)**: 도구 출력과 실패 원인을 호스트에 전달하는 단계이며, 정상 결과와 오류 사례를 동일한 처리 파이프라인으로 수렴시키는 기술적 기반이 된다.
- **정규화된 관찰값 전달(Normalized Observation)**: 신뢰 경계 표식을 부착한 결과를 다음 추론에 제공하는 단계를 뜻하며, 외부 출력이 모델 내부 정책에 미치는 영향을 통제 가능한 형태로 변환하는 필수적인 역할을 수행한다.

</details>

```text
호스트·검증기
    │ 1. 도구명•스키마•위험 정보 제공
    ▼
모델
    │ 2. 선택 도구•구조화 인자 제안
    ▼
호스트·검증기
    │ 3. 검증•승인된 호출 실행
    ▼
도구
    │ 실행 결과·오류 반환
    ▼
호스트·검증기
    │ 4. 정규화된 관찰값 전달
    ▼
모델
```

### 동작 원리

1. 도구명•스키마•위험 정보 제공: 호출 범위 명시
2. 선택 도구•구조화 인자 제안: 스키마 기반 후보 생성
3. 검증•승인된 호출 실행: 값•권한•업무 규칙 확인
4. 정규화된 관찰값 전달: **신뢰 경계 표식** 부착

#### 한줄 요약
- **검증된 호출•결과 정규화** 기반 안전 실행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **코드 샌드박스(Code Sandbox)**: 생성된 코드를 운영 시스템과 격리하고 실행 시간•메모리•파일 및 네트워크 입출력 권한을 제한해 실행하는 환경이며, 모델이 생성한 임의 코드가 호스트 자원에 미치는 영향을 통제 가능한 범위로 한정하는 기술적 기반이 된다.
- **플러그인(Plugin)**: 플랫폼에 설치되어 기능 묶음과 UI•도구를 함께 확장하는 배포 단위를 의미하며, 도구 묶음을 사용자가 선택적으로 활성화하고 라이프사이클을 관리할 수 있게 하는 핵심 아키텍처 요소이다.
- **함수 호출(Function Calling)**: 모델이 실행할 함수명과 구조화된 인자를 JSON 형식으로 제안하는 도구 호출 구현 방식이며, 구조화된 출력을 통해 호스트의 파싱•검증 부담을 줄이는 기술적 기반이 된다.

</details>

| 구분 | 도구 호출 | 플러그인(Plugin) | 함수 호출(Function Calling) |
|:---|:---|:---|:---|
| 적용 기준 | **전체 실행 제어** | **배포 단위 확장** | **구조화 인자 출력** |
| 핵심 특징 | **모델 제안·호스트 실행** 분리 | 플랫폼별 **라이프사이클** | 함수명·인자의 **JSON 생성** |
| 한계 | **권한 오용 위험** | **플랫폼 종속성** | **호스트 구현 부담** |

#### 한줄 요약
- 실행 제어는 **도구 호출**, 인자 출력은 함수 호출

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **부작용 통제(Side Effect Control)**: 데이터 변경•결제•전송 같은 비가역 행동에 승인•멱등성(동일 요청 반복 시 결과가 일치하는 성질)•감사 기록을 적용하는 운영 방식을 말하며, 자동화된 도구 실행으로 인한 실제 업무 영향을 예측 가능하고 추적 가능한 상태로 유지하는 주요 기전으로 작용한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잘못된 도구·인자 호출 | **허용 목록·JSON 스키마·업무 규칙** | **오실행** 차단 |
| 외부 결과의 지시 주입 | **비신뢰 데이터 처리·재진입 차단** | **간접 주입** 방지 |
| 변경·결제의 비가역 부작용 | **멱등성·HITL 승인·감사** | **비가역 피해** 축소 |

#### 한줄 요약
- **최소 권한•HITL** 기반 비가역 부작용 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **신뢰 경계(Trust Boundary)**: 모델 제안과 실제 실행 사이에서 권한•인자•정책을 검증하고 결과를 비신뢰 데이터로 정규화하는 분리 지점을 뜻하며, 모델의 추론 공간과 외부 시스템의 실행 공간을 명확히 구분하여 내부 정책이 외부 입력에 의해 변조되지 않도록 하는 필수적인 역할을 수행한다.

</details>

- 거대언어모델을 단순한 텍스트 생성기에서 실세계 시스템을 조작하는 지능형 실행기로 격상시키는 **핵심 상호작용 메커니즘(Tool Use / Model Proposal & Host Execution / JSON Schema & MCP / Trust Boundary & Sandbox)의 필수 아키텍처 표준**으로 확고히 자리 잡았으며, Model Context Protocol(MCP) 표준화 및 멀티 에이전트 도구 공유 생태계로 급속히 발전하는 가운데, 실무 엔터프라이즈 도구 연동 구축 시에는 **도구 목적과 인자 제약조건을 명문화한 JSON Schema 선언, 격리된 가상환경(Docker/gVisor) 기반의 코드 샌드박스 실행, 간접 프롬프트 주입(Indirect Prompt Injection) 방지를 위한 외부 반환값 정규화 및 데이터 변경·금융 거래에 대한 최소 권한(Least Privilege)과 HITL 승인 통제**를 결합하여 완벽한 도구 확장성과 시스템 보안성을 완성

#### 한줄 요약
- **행동 부작용•가역성** 대상 따라 권한과 승인 수준 결정
