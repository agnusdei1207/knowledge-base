## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **도구 호출(Tool Use)**: 대규모 언어 모델이 외부 기능과 인자를 제안하고 호스트가 이를 검증•승인•실행하여 결과를 모델에 돌려주는 연계 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **대규모 언어 모델(Large Language Model, LLM)**: 사용자 목표를 해석하여 호출할 외부 기능과 구조화된 인자를 제안하는 모델이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 정의/개념: LLM 제안과 호스트 검증•실행을 분리하는 **도구 호출 연계 방식**임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 배경/필요성: 텍스트 생성만으로는 외부 상태를 조회하거나 데이터베이스 업무를 변경할 수 없음.

#### 한줄 요약
- 모델은 도구•인자를 제안하고 호스트는 검증•실행한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **실행 책임 분리(Separation of Execution Responsibility)**: 모델이 도구 호출을 제안하되 실제 권한 확인과 실행은 신뢰 경계 안의 호스트가 담당하는 원칙을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **자바스크립트 객체 표기법 스키마(JavaScript Object Notation Schema, JSON Schema)**: 도구 인자의 자료형•필수 필드•허용 범위를 구조적으로 검증하는 명세이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **책임 축(Responsibility Axis)**: 모델의 호출 제안과 호스트의 권한 확인•실행 책임을 구분하는 기능 영역이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **검증 축(Validation Axis)**: 호출 인자•권한•업무 규칙의 유효성을 겹쳐 확인하는 기능 영역을 지칭한다.
- **결과 축(Result Axis)**: 도구 출력•오류를 비신뢰 관찰값으로 정규화하는 기능 영역이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **책임 축**: **LLM** 중심 도구•인자 제안 및 호스트 중심 실행을 결정하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **검증 축**: **JSON 스키마**•최소권한•업무 규칙 중첩을 확인하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **결과 축**: 출력•오류를 다음 판단의 비신뢰 관찰값으로 정규화하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **실행 책임 분리**와 **JSON 스키마** 검증으로 외부 기능을 호출한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 애플리케이션과 외부 데이터•도구의 연결 및 메시지 교환을 표준화한 프로토콜을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 실행 중개기가 외부 기능을 정해진 요청•응답 규격으로 호출하는 인터페이스이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **인간 참여형 통제(Human-in-the-Loop, HITL)**: 고위험 도구 실행 전에 사람이 맥락과 영향을 검토하고 승인하는 통제 기법을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

```text
                [도구 레지스트리]
                         |
                   [모델•라우터]
                         |
                   [실행 중개기]
                         |
                   [결과 처리기]
```

선의 의미: 도구 레지스트리의 명세를 모델•라우터가 참조하고, 실행 중개기의 신뢰 경계를 거쳐 결과 처리기에 연결되는 도구 호출 구조를 나타냄.

| 구성요소 | 책임 |
|:---|:---|
| 도구 레지스트리 | **MCP**•**API** 스키마•위험•권한을 제공함 |
| 모델•라우터 | **LLM**이 **JSON 스키마**에 맞는 인자•병렬 호출을 제안함 |
| 실행 중개기 | 인증•검증•**HITL** 승인•샌드박스 실행을 수행함 |
| 결과 처리기 | 결과•오류를 신뢰 경계에 따라 정규화함 |

#### 한줄 요약
- **MCP** 레지스트리와 실행 중개기•결과 처리기가 호출 책임을 분담한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **도구 결과(Tool Result)**: 외부 실행이 반환한 데이터나 오류를 다음 판단에 사용하도록 구조화한 비신뢰 관찰값을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **도구명•스키마•위험 정보 제공(Tool/Schema Provision)**: 모델에 허용 기능•인자 제약•부작용을 알리는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **선택 도구•구조화 인자 제안(Tool/Argument Proposal)**: 사용자 목표에 맞는 호출 후보와 인자를 생성하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **검증•승인된 호출 실행(Verified Execution)**: 값•대상•권한•업무 규칙을 확인해 제한 환경에서 실행하는 단계를 지칭한다.
- **실행 결과•오류 반환(Execution Return)**: 도구 출력과 실패 원인을 호스트에 전달하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **정규화된 관찰값 전달(Normalized Observation)**: 신뢰 경계를 표시한 결과를 다음 추론에 제공하는 단계를 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

```text
호스트•검증기
   │ 1. 도구명•스키마•위험 정보 제공
   ▼
모델
   │ 2. 선택 도구•구조화 인자 제안
   ▼
호스트•검증기
   │ 3. 검증•승인된 호출 실행
   ▼
도구
   │ 4. 실행 결과•오류 반환
   ▼
호스트•검증기
   │ 5. 정규화된 관찰값 전달
   ▼
모델
```

### 동작 원리

1. **도구명•스키마•위험 정보 제공**: 모델이 선택할 수 있는 기능과 인자 제약 및 부작용을 명시함.
2. **선택 도구•구조화 인자 제안**: 사용자 목표에 맞는 호출 후보를 생성함.
3. **검증•승인된 호출 실행**: 값•대상•권한•업무 규칙을 확인해 제한 환경에서 실행함.
4. **실행 결과•오류 반환**: 도구 출력과 실패 원인을 호스트에 전달함.
5. **정규화된 관찰값 전달**: **도구 결과**의 신뢰 경계를 표시해 다음 추론에 반영함.

#### 한줄 요약
- **검증•승인된 호출 실행** 후 **정규화된 관찰값 전달**로 결과를 반환한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **코드 샌드박스(Code Sandbox)**: 생성된 코드를 운영 시스템과 격리하고 시간•메모리•입출력 권한을 제한해 실행하는 환경이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **플러그인(Plugin)**: 플랫폼에 설치되어 기능•UI•도구 묶음을 확장하는 배포 단위를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **함수 호출(Function Calling)**: 모델이 실행할 함수명과 구조화된 인자를 제안하는 도구 호출 구현 방식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

| 판단 기준 | 도구 호출 | 플러그인 | 함수 호출 |
|:---|:---|:---|:---|
| 적용 기준 | **도구 호출**은 다양한 외부 기능을 활용함 | **플러그인**은 플랫폼 확장 묶음이 필요함 | **함수 호출**은 구조화 인자가 필요함 |
| 핵심 특징 | 외부 기능 활용의 상위 개념임 | 설치형 기능•UI 확장 묶음임 | 함수명•인자를 구조화하여 반환함 |
| 한계 | 권한 오용 및 결과 주입 위험이 있음 | 플랫폼에 종속됨 | 실행 및 값 검증은 호스트 책임임 |

> 요약: **도구 호출**은 상위 실행 개념이고 **플러그인**과 **함수 호출**은 구현 방식임.

#### 한줄 요약
- 생성 코드는 **코드 샌드박스**에서 실행하고 기능 묶음은 **플러그인**으로 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **부작용 통제(Side Effect Control)**: 데이터 변경•결제•전송 같은 비가역 행동에 승인•멱등성•감사 기록을 적용하는 운영 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잘못된 도구•인자로 생기는 오호출 | 허용 목록•**JSON 스키마**•업무 규칙을 검증함 | 부적절한 도구 실행을 차단함 |
| 도구 결과에 섞이는 지시문 주입 | **도구 결과**를 비신뢰 관찰값으로 분리함 | 다음 추론의 정책 우회를 방지함 |
| 환불•배송지 변경의 업무 부작용 | **부작용 통제**로 권한 분리•HITL•감사를 적용함 | 실제 업무 영향을 통제함 |

#### 한줄 요약
- **부작용 통제**에 조회•변경 권한 분리와 HITL•감사를 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **신뢰 경계(Trust Boundary)**: 모델 제안과 실제 실행 사이에서 권한•인자•정책을 검증하고 결과를 비신뢰 데이터로 정규화하는 분리 지점을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

- 외부 상태•업무 실행은 **도구 호출**, 변경 작업은 **HITL** 승인 후 실행하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **신뢰 경계**와 **HITL**로 오호출의 업무 영향을 통제한다. 체계 적용
