## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **도구 호출(Tool Use)**: LLM이 외부 기능·인자 제안 시 호스트가 검증·승인·실행 후 결과 반환하는 연계 방식. 모델과 외부 시스템 간 신뢰 경계를 설정하여 안전한 자원 접근을 보장하는 아키텍처.
- **LLM(Large Language Model)**: 목표 해석 기반 외부 기능·인자 제안 엔진. 추론 불가능한 실시간 조회·변경 업무를 외부 기능에 위임하는 호출 제안자(Caller).

</details>

- 개념: LLM의 호출 제안과 호스트의 검증·실행을 분리하는 도구 호출 연계 방식. 자율성과 통제 가능성을 동시에 충족하여 실질적 업무 가치 창출.
- 배경: 단순 텍스트 생성만으로는 외부 상태 조회/변경 불가. 외부 실행 주체의 안전한 중개 메커니즘 필수.

#### 한줄 요약
- 모델은 도구•인자를 제안하고 호스트는 검증•실행 체계 적용

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **실행 책임 분리(Separation of Execution Responsibility)**: 모델은 제안, 호스트는 권한 확인·실행을 담당하여 오류의 시스템 침해 방지.
- **JSON 스키마(JSON Schema)**: 도구 인자의 자료형·필수 필드·허용 범위를 구조적으로 검증하여 실행 실패·오류 차단.
- **책임 축(Responsibility Axis)**: 모델의 호출 제안과 호스트의 확인·실행 책임을 분리하여 소재 추적성 확보.
- **검증 축(Validation Axis)**: 인자·권한·업무 규칙을 다층 검증하여 비인가 행위 방지.
- **결과 축(Result Axis)**: 도구 출력·오류를 비신뢰 관찰값으로 정규화하여 정책 우회 방지.

</details>

- **책임 축**: **LLM**이 도구와 인자를 제안하고, 호스트가 실행 권한을 보유하도록 결정하여 실무 환경에서 모델의 환각이나 오류가 곧바로 실제 시스템 변경으로 이어지지 않도록 하는 유연한 대응과 지속적 최적화를 지원함.
- **검증 축**: **JSON 스키마**로 인자 형식을, 최소권한 원칙으로 호출 범위를, 업무 규칙으로 도메인 제약을 각각 확인하여 실무 환경에서 다층 방어가 필요한 상황의 유연한 대응과 지속적 최적화를 지원함.
- **결과 축**: 외부 출력과 오류를 다음 판단의 비신뢰 관찰값으로 정규화하여 실무 환경에서 프롬프트 인젝션(악성 지시 삽입)이나 결과값 조작 시도에 따른 정책 우회를 방지하는 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **실행 책임 분리**와 **JSON 스키마** 검증으로 외부 기능을 호출 체계 적용

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 인공지능 애플리케이션과 외부 데이터•도구의 연결 및 메시지 교환을 표준화한 프로토콜을 뜻하며, 도구 명세의 등록과 조회를 위한 공통 인터페이스를 제공하여 다양한 도구를 일관된 방식으로 통합하는 필수적인 역할을 수행한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 실행 중개기가 외부 기능을 정해진 요청•응답 규격으로 호출하기 위한 표준 인터페이스이며, 내부 도구 호출 체계를 외부 시스템과 연결하는 기술적 기반이 된다.
- **인간 참여형 통제(Human-in-the-Loop, HITL)**: 고위험 도구 실행 전에 사람이 맥락과 영향을 검토하고 승인하는 통제 기법을 의미하며, 자동화된 실행에서 발생할 수 있는 비가역적 업무 영향을 사람이 사전에 차단할 수 있게 하는 핵심 아키텍처 요소이다.

</details>

```text
                [도구 레지스트리]
                         |
                   [모델•라우터]
                         |
                   [실행 중개기]
                         |
                   [결과 처리기]
```

선의 의미: 도구 레지스트리의 명세를 모델•라우터가 참조하고, 실행 중개기의 신뢰 경계를 거쳐 결과 처리기에 연결되는 도구 호출 구조를 나타냄.

| 구성요소 | 책임 |
|:---|:---|
| 구성요소 | 책임 |
|:---|:---|
| 도구 레지스트리 | MCP와 API 스키마, 위험 등급, 권한 범위 제공 |
| 모델·라우터 | LLM의 JSON 스키마 기반 인자 생성 및 다중 병렬 호출 제안 |
| 실행 중개기 | 인증, 스키마 검증, HITL 승인, 샌드박스 내 실행 |
| 결과 처리기 | 외부 출력/오류의 신뢰 경계 표식 부착 정규화 |

#### 한줄 요약
- **MCP** 레지스트리와 실행 중개기•결과 처리기가 호출 책임을 분담 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **도구 결과(Tool Result)**: 외부 실행이 반환한 데이터나 오류를 다음 판단에 사용하도록 구조화한 비신뢰 관찰값을 말하며, 신뢰 경계 밖의 입력임을 표시하여 모델이 외부 출력을 내부 명령과 동일하게 취급하지 않도록 하는 주요 기전으로 작용한다.
- **도구명•스키마•위험 정보 제공(Tool/Schema Provision)**: 모델에 허용 기능 목록•인자 제약 조건•부작용 가능성을 알리는 초기 단계이며, 모델이 호출 가능 범위를 사전에 인지하도록 하는 기술적 기반이 된다.
- **선택 도구•구조화 인자 제안(Tool/Argument Proposal)**: 사용자 목표에 맞는 호출 후보와 인자를 생성하는 단계이며, 자유 텍스트가 아닌 구조화 형식으로 출력을 제한하여 호출 의도를 명확히 하는 기술적 기반이 된다.
- **검증•승인된 호출 실행(Verified Execution)**: 값•대상•권한•업무 규칙을 확인해 제한된 샌드박스 환경에서 실행하는 단계를 지칭하며, 다단계 확인을 통해 비인가 실행을 차단한다.
- **실행 결과•오류 반환(Execution Return)**: 도구 출력과 실패 원인을 호스트에 전달하는 단계이며, 정상 결과와 오류 사례를 동일한 처리 파이프라인으로 수렴시키는 기술적 기반이 된다.
- **정규화된 관찰값 전달(Normalized Observation)**: 신뢰 경계 표식을 부착한 결과를 다음 추론에 제공하는 단계를 뜻하며, 외부 출력이 모델 내부 정책에 미치는 영향을 통제 가능한 형태로 변환하는 필수적인 역할을 수행한다.

</details>

```text
호스트·검증기
   │ 1. 도구명·스키마·위험 정보 제공
   ▼
모델
   │ 2. 선택 도구·구조화 인자 제안
   ▼
호스트·검증기
   │ 3. 검증·승인된 호출 실행
   ▼
도구
   │ 4. 실행 결과·오류 반환
   ▼
호스트·검증기
   │ 5. 정규화된 관찰값 전달
   ▼
모델
```

### 동작 원리

1. **도구명•스키마•위험 정보 제공**: 호스트가 모델이 선택할 수 있는 기능과 인자 제약 및 부작용 가능성을 명시하여, 모델이 호출 가능 범위 내에서만 제안을 생성하도록 함.
2. **선택 도구•구조화 인자 제안**: 사용자 목표에 맞는 호출 후보를 생성하며, 인자가 **JSON 스키마**를 따르도록 강제하여 자유 텍스트로 인한 파싱 오류를 방지함.
3. **검증•승인된 호출 실행**: 값•대상•권한•업무 규칙을 확인해 제한된 샌드박스 환경에서 실행하며, 고위험 작업은 **HITL** 승인을 거쳐 실행함.
4. **실행 결과•오류 반환**: 도구의 정상 출력과 실패 원인을 호스트에 전달하며, 오류 정보를 다음 시도의 인자 보정에 활용함.
5. **정규화된 관찰값 전달**: **도구 결과**에 신뢰 경계 표식을 부착하여 다음 추론에 반영하며, 외부 출력이 내부 정책을 우회하는 경로를 차단함.

#### 한줄 요약
- **검증·승인된 호출 실행** 후 **정규화된 관찰값 전달**로 결과를 반환 체계 적용.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **코드 샌드박스(Code Sandbox)**: 생성된 코드를 운영 시스템과 격리하고 실행 시간•메모리•파일 및 네트워크 입출력 권한을 제한해 실행하는 환경이며, 모델이 생성한 임의 코드가 호스트 자원에 미치는 영향을 통제 가능한 범위로 한정하는 기술적 기반이 된다.
- **플러그인(Plugin)**: 플랫폼에 설치되어 기능 묶음과 UI•도구를 함께 확장하는 배포 단위를 의미하며, 도구 묶음을 사용자가 선택적으로 활성화하고 라이프사이클을 관리할 수 있게 하는 핵심 아키텍처 요소이다.
- **함수 호출(Function Calling)**: 모델이 실행할 함수명과 구조화된 인자를 JSON 형식으로 제안하는 도구 호출 구현 방식이며, 구조화된 출력을 통해 호스트의 파싱•검증 부담을 줄이는 기술적 기반이 된다.

</details>

| 판단 기준 | 도구 호출 | 플러그인 | 함수 호출 |
|:---|:---|:---|:---|
| 적용 기준 | **도구 호출**은 다양한 외부 기능과 샌드박스 실행을 모두 포괄하는 상위 개념임 | **플러그인**은 플랫폼에 설치되어 기능과 UI를 묶음으로 확장하는 경우에 적합함 | **함수 호출**은 구조화된 인자 생성이 필요하고 실행 부담을 호스트에 위임하는 경우에 적합함 |
| 핵심 특징 | 모델 제안과 호스트 실행을 분리하여 자율성과 통제성을 동시에 확보함 | 플랫폼 종속적이며 설치와 라이선스 관리 절차를 통해 배포됨 | 모델이 함수명과 인자 JSON을 반환하고 실행은 호스트가 담당함 |
| 한계 | 권한 오용과 결과 주입 위험에 대한 추가 통제 레이어가 필요함 | 플랫폼 종속성으로 인해 멀티플랫폼 환경에서는 중복 구현이 발생함 | 값 검증과 실제 실행이 모두 호스트 책임이므로 호스트 구현 부담이 큼 |

> 요약: **도구 호출**은 상위 실행 개념이고 **플러그인**과 **함수 호출**은 각각 배포 단위와 출력 형식 측면의 구현 방식임.

#### 한줄 요약
- 생성 코드는 **코드 샌드박스**에서 실행하고 기능 묶음은 **플러그인**으로 제공 체계 적용

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **부작용 통제(Side Effect Control)**: 데이터 변경•결제•전송 같은 비가역 행동에 승인•멱등성(동일 요청 반복 시 결과가 일치하는 성질)•감사 기록을 적용하는 운영 방식을 말하며, 자동화된 도구 실행으로 인한 실제 업무 영향을 예측 가능하고 추적 가능한 상태로 유지하는 주요 기전으로 작용한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 잘못된 도구•인자로 생기는 오호출 | 허용 목록(Allowlist)•**JSON 스키마**•업무 규칙을 다단계로 검증함 | 비인가 도구 실행과 형식이 맞지 않는 인자로 인한 오작동을 차단함 |
| 도구 결과에 섞이는 지시문 주입 | **도구 결과**를 비신뢰 관찰값으로 분리하고 정책 재진입을 차단함 | 외부 출력에 포함된 악성 지시문이 다음 추론의 정책을 우회하는 것을 방지함 |
| 환불•배송지 변경의 업무 부작용 | **부작용 통제**로 변경•조회 권한을 분리하고 **HITL**•감사 로그를 적용함 | 비가역적 업무 변경의 영향 범위를 통제 가능한 수준으로 한정함 |

#### 한줄 요약
- **부작용 통제**에 조회•변경 권한 분리와 HITL•감사를 적용 체계 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **신뢰 경계(Trust Boundary)**: 모델 제안과 실제 실행 사이에서 권한•인자•정책을 검증하고 결과를 비신뢰 데이터로 정규화하는 분리 지점을 뜻하며, 모델의 추론 공간과 외부 시스템의 실행 공간을 명확히 구분하여 내부 정책이 외부 입력에 의해 변조되지 않도록 하는 필수적인 역할을 수행한다.

</details>

- 외부 상태 조회와 업무 실행은 **도구 호출** 체계로 분리하고, 실제 데이터 변경이 발생하는 작업은 **HITL** 승인을 거쳐 실행하여 실무 환경에서 자동화 효율과 통제 가능성을 동시에 확보하는 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **신뢰 경계**와 **HITL**로 오호출의 업무 영향을 통제하는 책임 분리 체계 적용.
