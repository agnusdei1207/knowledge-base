## 미리 알고가기

- **OWASP LLM Top 10**: OWASP LLM Top 10은 LLM 기반 애플리케이션의 우선 보안 위험을 정리한 실무 기준임
- **최신 OWASP GenAI 2025**: 최신 OWASP GenAI 2025는 모델 자체보다 앱·데이터·운영 생명주기 위험을 함께 본다는 점이 중요함
- **항목 해석 관점**: 각 항목은 단일 모델 문제가 아니라 프롬프트와 RAG와 권한과 공급망이 얽힌 시스템 위험으로 해석해야 함

## Ⅰ. 개요

- **정의/개념**: LLM 앱의 10대 위험과 완화 지침이다
- **배경/필요성**: 모델·데이터·도구 위험을 공통 기준으로 점검한다

### 쉽게 이해하기 (학습용)

- 챗봇 모델과 연결된 문서함·검색창·실행 도구의 사고 지점을 같은 번호로 표시하는 지도다.

## Ⅱ. 특징

- 앱·데이터·도구 경계까지 봐 연쇄 공격을 찾는다
- 위험별 사례·완화책은 위협 모델링 누락을 줄인다
- 한 공격 경로는 여러 항목의 복합 피해를 만들 수 있다
- 판본 식별은 항목 번호 혼용과 잘못된 적용을 막는다
- 프롬프트 밖 비밀 관리는 자격증명 노출을 막는다

### 쉽게 이해하기 (학습용)

- 한 번의 악성 지시가 정보 노출과 도구 오용을 함께 만들 수 있어 관련 위험 항목을 연결해 본다.

## Ⅲ. 아키텍처 및 구성요소

```text
       [공급망·학습]
             │
[프롬프트] ─ [시스템] ─ [정보]
             │
      ┌──────┴──────┐
    [도구]        [자원]
```

| 설계 요소 | 설명 |
|:---|:---|
| 프롬프트 경계 | 지시·데이터 분리 |
| 공급망 경계 | 데이터·모델 출처 검증 |
| 정보 경계 | 민감정보·사실성 확인 |
| 도구 경계 | 실행 권한·사용자 승인 |
| 자원 경계 | 토큰·시간·비용 예산 |

> 요약: 열 가지 위험을 서비스 경계별 통제로 연결한다

### 쉽게 이해하기 (학습용)

- 열 가지 위험을 입력·학습·검색·출력·도구·사용량 경계에 붙이면 담당 통제가 보인다.

## Ⅳ. 원리 및 절차 흐름도

```text
목록화
 ↓
경계 표시
 ↓
매핑
 ↓
검증 지정
 ↓
잔여 판정
 ↓
재평가
```

| 절차 | 설명 |
|:---|:---|
| 자산 목록화 | 모델·데이터·도구 식별 |
| 경계 표시 | 신뢰·비신뢰 통로 구분 |
| 위험 매핑 | 공격 경로와 항목 연결 |
| 검증 지정 | 예방·탐지·복구 통제 결정 |
| 잔여 판정 | 배포 수용 여부 결정 |
| 변경 재평가 | 구조 변경 시 매핑 갱신 |

> 요약: 경계에 위험을 매핑하고 통제·잔여 위험을 재평가한다

### 쉽게 이해하기 (학습용)

- 시스템 경계에 위험 번호와 담당자를 붙이고 통제를 공격으로 검증한 뒤 실패한 경계를 보완한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 2023/24판 | 2025판 |
|:---|:---|:---|
| 핵심 특징 | 구판 위험 분류 | 앱·운영 위험을 확대한 분류 |
| 적용 기준 | 기존 평가 식별자 해석 | 현재 서비스 통제 매핑 |
| 주요 위험 | 최신 위험 누락 | 판본 번호 혼용 |

> 요약: 구판은 이력 해석, 2025판은 현재 통제에 적용한다

### 쉽게 이해하기 (학습용)

- 구판은 서비스 거부를 중심으로 봤고 2025판은 예상 밖 비용과 프롬프트·검색 벡터 위험까지 넓혔다.

## Ⅵ. 실무 사례

1. 사내 챗봇의 문서·검색·출력 위험을 매핑한다
2. 에이전트의 인젝션·과도한 권한 결합을 검증한다

### 쉽게 이해하기 (학습용)

- 사내 챗봇은 외부 문서가 검색과 출력을 거치는 경로마다 위험 항목과 접근 권한을 연결한다.
- 실행형 에이전트는 악성 지시가 실제 도구 권한으로 이어지는 결합 사고를 배포 전에 검증한다.

## Ⅶ. 결론

- 2025판 위험을 서비스 경계에 매핑해 변경 시 재평가한다.

### 쉽게 이해하기 (학습용)

- 최신 위험 번호를 실제 시스템 경계에 붙여 통제 책임자와 재검증 조건을 정해야 한다.
