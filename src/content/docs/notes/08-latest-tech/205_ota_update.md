## 미리 알고가기

- **OTA Update**: 무선 통신을 통해 소프트웨어를 원격 갱신하는 방식
- **업데이트 범위**: SOTA(SW 중심), FOTA(펌웨어 포함)로 구분됨
- **핵심 요소**: 보안 검증, 롤백, 중단 복구 체계가 필수적임



## Ⅰ. 개요

- **정의/개념**: 서명된 차량 SW를 원격 배포·설치하는 체계
- **배경/필요성**: 출시 후 패치·결함·기능 개선을 신속 확산

### 쉽게 이해하기 (학습용)

- 서명과 호환성을 검증하고 안전하게 갱신하는 체계임

## Ⅱ. 특징

- 이미지·매니페스트 결속이 무결성을 검증한다.
- 단계 배포가 결함 확산을 조기에 중단한다.
- A/B 복구·롤백 방지가 가용성과 보안을 지킨다.
- R156이 업데이트 관리·증적 책임을 요구한다.

### 쉽게 이해하기 (학습용)

- 서명 검증, 단계적 배포, 이전 정상본 복구가 핵심임

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| Signed Package | 무결성 및 서명된 업데이트 데이터 |
| SUMS/Backend | 배포 대상 관리 및 전체 이력 관리 |
| Compatibility | VIN/ECU 조합의 설치 호환성 검증 |
| Secure Installer | 안전 조건 내 설치 실행 및 검증 |
| Boot/Recovery | 부팅 확인 및 오류 시 자동 복구 |

> 요약: 신뢰 기반 배포 및 부팅 후 health 확인 체계임

### 쉽게 이해하기 (학습용)

- 중앙은 어느 차량이 받을지 정하고 차량은 서명과 부품 조합을 확인해 설치하며, 새 버전이 정상 부팅됐는지 결과를 다시 보고함

## Ⅳ. 원리 및 절차 흐름도

서명패키지
 ↓
단계적배포
 ↓
조건검증
 ↓
정상부팅?
 ├─ 아니오: 복구
 └─ 예: 활성화

| 절차 | 설명 |
|:---|:---|
| 생성·서명 | 생성·서명을 수행하고 결과를 검증함 |
| 검증·승인 | 검증·승인을 수행하고 결과를 검증함 |
| 대상·단계 배포 | 대상·단계 배포을 수행하고 결과를 검증함 |
| 차량 설치 | 차량 설치을 수행하고 결과를 검증함 |
| 활성화·복구 | 활성화·복구을 수행하고 결과를 검증함 |

> 요약: 안전 승인과 호환성 검증 기반 단계적 배포함

### 쉽게 이해하기 (학습용)

- 새 프로그램을 검증·승인한 뒤 맞는 차량 몇 대부터 보내고, 차량이 배터리와 서명을 확인해 설치하며 정상 부팅이 안 되면 이전본으로 돌아감

## Ⅴ. 종류 및 비교

| 판단 기준 | In-place Update | A/B Slot Update | Recovery Partition |
|:---|:---|:---|:---|
| 핵심 특징 | 현재 영역을 직접 교체함 | 비활성 slot에 설치 후 boot slot을 전환함 | 별도 복구 환경에서 주 영역을 수리·재설치함 |
| 적용 기준 | journal·재시도 또는 정비소 복구가 필요함 | boot health 실패 시 이전 slot로 전환함 | 복구 image로 부팅해 정상 package를 다시 적용함 |
| 주요 위험 | 저장공간은 작지만 중단 위험이 큼 | 이중 저장공간이 필요하나 무중단 복구에 유리함 | 복구 영역·절차 관리가 필요하고 저수준 ECU에 적합함 |

> 요약: 안정성과 공간 효율에 따라 설치 방식 선택함

### 쉽게 이해하기 (학습용)

- 현재 책을 바로 고치면 공간은 적게 들고, 새 책을 옆에 완성한 뒤 바꾸면 실패 시 되돌리기 쉬우며, 별도 복구 설명서는 망가진 책을 다시 만듦

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 완성차 OTA 플랫폼은 동일 ECU hardware·현재 version cohort의 1% 차량에 A/B package를 배포하고 boot health·진단 오류 임계치를 넘으면 확대를 중단해 이전 slot로 복구함
- repository signing key가 노출되면 OEM은 offline root로 key를 revoke·rotate하고 metadata version을 높여 재배포하며 신뢰 root 갱신이 불가능한 ECU는 정비소 복구 대상으로 격리함

## Ⅶ. 결론

- 서명·단계 배포·복구 검증 후 OTA 승인

### 쉽게 이해하기 (학습용)

- 무선으로 파일을 보내는 기능보다 누가 어떤 차량에 무엇을 보냈고 실패·키 유출 때 어떻게 안전하게 복구했는지 끝까지 증명하는 것이 핵심임
