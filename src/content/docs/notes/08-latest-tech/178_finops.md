## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **핀옵스(FinOps)**: Finance와 DevOps를 결합한 명칭으로, 기술•재무•사업 조직이 기술 지출의 사업 가치를 공동 최적화하는 운영 프레임워크이자 문화적 실천을 의미한다.
- **단위 경제성(Unit Economics)**: 요청•고객•거래 등 사업 가치 단위당 기술 비용을 의미한다.

</details>

- 정의: **핀옵스** 기반 기술•재무•사업 조직이 데이터 기반 의사결정과 재무 책임으로 기술 지출의 사업 가치를 공동 최적화하는 운영 프레임워크이자 문화적 실천임이다.
- 배경/필요성: 중앙 청구서만으로는 **사용 주체•제품 가치•낭비 원인** 연결하기 어려운 한계가 발생함.

#### 한줄 요약

- 누가 왜 썼고 그 지출이 어떤 제품 가치로 이어졌는지를 기술•재무•사업 팀이 함께 판단한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **쇼백(Showback)**: 비용을 사용 조직에 보여 주되 실제 예산에는 부과하지 않는 방식이다.
- **차지백(Chargeback)**: 사용 조직의 실제 예산에 배분된 기술 비용을 부과하는 방식이다.

</details>

- 팀•제품•환경별 **비용 가시성•할당** 핵심임.
- 쇼백•차지백 기반 **분산 책임** 핵심임.
- 정보•최적화•운영을 반복하는 **Inform•Optimize•Operate** 핵심임.
#### 한줄 요약

- 무조건 적게 쓰는 것이 아니라 품질을 지키며 사용법과 구매 방식을 개선한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **비용 할당**: 직접•공유 기술 비용을 팀•제품•환경 등 책임 단위에 귀속하는 과정을 의미한다.
- **거버넌스**: 예산•이상 지출•구매 약정•성과를 공동 규칙과 책임으로 관리하는 체계로 정의된다.
- **청구 데이터**: 제공자별 요금•할인•세금•약정 비용을 담은 원천 자료을 의미한다.
- **사용량 데이터**: 팀•제품•환경별 자원 소비량을 측정한 원천 자료이다.
- **비용 공개**: 쇼백으로 책임 단위별 비용 정보를 제공하는 개념을 의미한다.
- **비용 부과**: 차지백으로 책임 단위의 실제 예산에 비용을 반영하는 개념로 정의된다.
- **수요 예측**: 과거 사용량과 사업 계획으로 미래 자원 수요와 비용을 추정하는 개념을 말한다.
- **비용 최적화**: 크기 조정•약정•중지로 사업 가치 대비 비용을 개선하는 개념을 말한다.
- **사업 가치**: 기술 지출이 지원하는 매출•거래•고객 경험 등의 성과을 말한다.

</details>

```text
 [청구 데이터]   [사용량 데이터]
        \             /
          [비용 할당]
           /       \
    [비용 공개] [비용 부과]
           \       /
          [수요 예측]
               |
          [비용 최적화]
           /       \
    [사업 가치] [거버넌스]
```

선의 의미: 청구•사용량 자료가 비용 할당의 근거가 되고, 공개•부과된 비용은 수요 예측과 최적화를 거쳐 사업 가치와 거버넌스로 평가된다.

| 구성요소 | 책임 |
|:---|:---|
| 청구 데이터 | 공급자 비용•가격•할인 정규화 |
| 사용량 데이터 | 팀•제품•환경별 자원 소비 측정 |
| 비용 할당 | 직접•공유 비용을 책임 단위에 귀속 |
| 비용 공개 | 팀별 비용 정보 제공 |
| 비용 부과 | 팀 예산에 실제 비용 반영 |
| 수요 예측 | 미래 자원 수요•비용 추정 |
| 비용 최적화 | 사용량•요율•약정 개선 |
| 사업 가치 | 단위 경제성•품질 성과 평가 |
| 거버넌스 | 예산•이상 지출•성과 관리 |

#### 한줄 요약

- 총고지서를 제품별로 나눈 뒤 다음 사용을 예측하고 가치가 큰 개선부터 실행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비용 정규화**: 공급자마다 다른 청구 항목과 사용량을 공통 분류•단위로 변환하는 과정로 정의된다.
- **요율 최적화**: 수요 예측에 맞춰 온디맨드•약정•할인 구매 구성을 조정하는 활동이다.

</details>

```text
[청구•사용량 데이터]
         │ 1. 비용•사용량 정규화
         ▼
     [비용 할당]
         │ 2. 직접•공유 비용 귀속
         ▼
   [쇼백•차지백]
         │ 3. 책임 조직 비용 공개
         ▼
    [예측•최적화]
         │ 4. 사용량•요율 개선안
         ▼
[사업 가치•거버넌스] ── 5. 단위 가치•정책 환류 ──▶ [비용 할당]
```

### 동작 원리

1. 비용•사용량 정규화: 청구 항목을 공통 분류로 변환
2. 직접•공유 비용 귀속: 태그•계정•사용량으로 소유자 배분
3. 책임 조직 비용 공개: 쇼백•차지백으로 행동 신호 제공
4. 사용량•요율 개선안: 낭비 제거•규모 조정•약정 검토
5. 단위 가치•정책 환류: 품질•단위 비용으로 정책 갱신

#### 한줄 요약

- 팀별 고지서를 보여 주고 개선한 뒤 요청당 비용과 서비스 품질이 나아졌는지 확인한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 비용 처리**: 공용 기술 비용을 사용 조직에 배분하지 않고 중앙 조직이 부담하는 방식을 말한다.
- **공유 비용**: 클러스터•네트워크•지원 조직처럼 여러 제품과 팀이 함께 사용해 직접 귀속하기 어려운 비용을 말한다.

</details>

| 비용 책임 방식 | 쇼백 | 차지백 | 중앙 비용 처리 |
|:---|:---|:---|:---|
| 적용 기준 | **자율 개선** 유도 | **비용 회수•강한 책임** | **초기•공용 기반 비용** |
| 핵심 특징 | 팀별 **비용 정보 제공** | 팀 예산에 **실제 비용 부과** | **중앙 조직** 비용 부담 |
| 한계 | **행동 변화 강제력** 부족 | **배분 분쟁•공유비 왜곡** | **사용 책임•최적화 동기** 약화 |

#### 한줄 요약

- 고지서만 보여 줄지 실제 예산에서 낼지 회사 공용비로 둘지를 비용 성숙도에 맞춰 정한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **커버리지**: 전체 적격 사용량 가운데 할인 약정이 적용된 비율이다.
- **활용률**: 구매한 약정 용량 가운데 실제 워크로드가 사용한 비율로 정의된다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 일정 기간에 달성하기로 정한 사용자 중심 서비스 품질 목표로 정의된다.
- **쿠버네티스(Kubernetes)**: 컨테이너화된 워크로드의 배포•확장•운영을 자동화하는 플랫폼을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 태그 누락•공유 비용 미배분 | 계정•태그•사용량 기반 **단계적 할당** | **비용 책임 정확도** 향상 |
| 할인 구매 후 **유휴 약정** | **수요 예측•커버리지•활용률** 공동 관리 | **약정 비용 낭비** 방지 |
| 절감으로 **서비스 품질 저하** | **SLO•단위 경제성** 동시 평가 | **비용•가치 균형** |

#### 한줄 요약

- 공유 **쿠버네티스** 비용은 네임스페이스 사용량으로 배분하되 **SLO** 및 거래당 비용을 함께 본다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **SLO 유지 조건**: 비용 절감 뒤에도 사용자 품질 목표를 계속 충족하는 기준을 말한다.
- **가치 최적화**: 단순 지출 감축이 아니라 품질을 유지하며 사업 성과 단위당 기술 비용을 개선하는 활동로 정의된다.

</details>

- **단위 경제성** 개선되고 **SLO** 유지되는 비용 최적화만을 적용함.

#### 한줄 요약

- **SLO** 활용 유지하며 사업 가치 단위당 기술 비용 최적화
