## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 오케스트레이션(Agent Orchestration)**: 목표 달성을 위해 에이전트•도구의 실행 경로와 상태•정책•복구를 통합 조정하는 관리 계층.
- **워크플로(Workflow)**: 작업 순서와 조건 분기, 반복, 완료 상태를 명시한 실행 절차.

</details>

- 정의: 에이전트•도구의 경로•상태•정책•복구를 조정하는 **오케스트레이션**
- 배경/필요성: 임의 호출 연결로는 실패 후 실행 분기 재현•상태 복구 불가

#### 한줄 요약

- **워크플로** 경로•상태•승인•복구 통합 조정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워크플로 그래프(Workflow Graph)**: 작업을 노드로, 실행 순서와 조건 분기를 전이로 표현한 구조.
- **라우터(Router)**: 현재 상태와 정책을 평가하여 다음 실행 경로를 선택하는 구성요소.
- **체크포인트(Checkpoint)**: 실패나 중단 뒤 이어서 실행할 수 있도록 단계 상태를 저장한 지점으로 정의된다.

</details>

- **워크플로 그래프**: 순차•조건•반복 경로 정의
- **라우터**: 상태에 따라 다음 실행 경로 선택
- **체크포인트**: 실패 지점부터 실행 재개
- **정책 통제**: 권한•승인•비용•오류 단계별 관리

#### 한줄 요약

- **워크플로•체크포인트•승인 지점** 사전 정의

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 실행 전에 사람이 근거와 영향을 검토하고 승인 여부를 결정하는 통제 방식.
- **스케줄러(Scheduler)**: 의존성과 가용 능력에 따라 실행 시점을 배정하는 구성요소이다.
- **상태 저장소(State Store)**: 단계별 입력•결과•승인•오류를 보존하는 구성요소이다.
- **관측성(Observability)**: 추적•로그•지표를 통해 워크플로 내부 상태와 변화를 파악하는 능력이다.
- **추적 식별자(Trace Identifier, Trace ID)**: 여러 단계의 호출과 결과를 하나의 실행 흐름으로 연결하는 식별자이다.

</details>

- **스케줄러•HITL** 및 Trace ID 기반 실행•승인•추적 연결

```text
                       [워크플로 그래프]
                    /           |           \
       [라우터•스케줄러] [상태•체크포인트] [정책•승인]
                    \           |           /
                         [관측•감사]
```

선의 의미: 워크플로의 실행•상태•정책 경계를 관측•감사로 추적하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 워크플로 그래프 | 작업 노드와 조건 전이 정의 |
| 라우터•스케줄러 | 상태•의존성에 따른 다음 실행 결정 |
| 상태•체크포인트 | **상태 저장소** 기반 단계 상태 저장•복구 |
| 정책•승인 | **HITL•권한** 및 예산 강제 |
| 관측•감사 | **관측성•Trace ID** 기반 상태 추적 |

#### 한줄 요약

- **라우터•상태** 및 정책•관측 계층의 경로 통제

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **멱등성(Idempotency)**: 같은 작업을 재실행해도 결제•전송 같은 부작용이 중복되지 않는 성질이다.
- **상태 전이(State Transition)**: 실행 결과와 조건에 따라 워크플로의 현재 단계를 다음 단계로 변경하는 과정으로 정의된다.
- **체크포인트 상태 복원(Checkpoint State Restoration)**: 저장된 단계별 입력•결과•승인•오류를 불러와 중단 시점의 실행 상태를 재구성하는 절차.
- **권한•예산•승인 판정(Authorization/Budget/Approval Evaluation)**: 현재 작업의 정책 조건을 평가해 실행 허용 여부를 결정하는 절차.
- **실행 경로 허용(Execution Path Authorization)**: 판정된 상태와 조건에 맞는 다음 노드의 실행을 승인하는 절차로 정의된다.
- **멱등키 기반 작업 실행(Idempotent Key-based Execution)**: 재시도 요청을 식별하는 키를 이용해 중복 부작용 없이 작업을 수행하는 절차로 정의된다.
- **결과 저장•상태 전이(Result Storage/State Transition)**: 실행 기록을 저장하고 결과에 따라 후속 단계를 결정하는 절차이다.

</details>

```text
오케스트레이터
   │ 1. 체크포인트 상태 복원
   ├──────────────────────┐
   │ 종료 상태 전까지     │
   └──────────┬───────────┘
   ▼
정책 엔진
   │ 2. 권한•예산•승인 판정
   │ 3. 실행 경로 허용
   ▼
오케스트레이터
   │ 4. 멱등키 기반 작업 실행
   ▼
에이전트•도구
   │ 실행 결과•오류 반환
   ▼
오케스트레이터
   │ 5. 결과 저장•상태 전이
   ▼
상태 저장소
```

### 동작 원리

1. 체크포인트 상태 복원: 중단 지점의 입력•결과•실행 상태 재구성
2. 권한•예산•승인 판정: 현재 노드의 정책 조건 평가
3. 실행 경로 허용: 상태와 조건에 맞는 다음 노드 선택
4. 멱등키 기반 작업 실행: 재시도 시 **멱등성** 보장
5. 결과 저장•상태 전이: 실행 기록 저장과 후속 경로 결정

#### 한줄 요약

- **체크포인트 복원•정책 판정** 후 결과•상태 저장

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **워크플로형(Workflow-based)**: 사전에 정의한 그래프와 상태 전이에 따라 실행을 통제하는 조정 방식.
- **자율 라우팅형(Autonomous Routing-based)**: 모델이 관찰 결과에 따라 역할이나 도구와 다음 경로를 선택하는 방식으로 정의된다.
- **혼합형(Hybrid-based)**: 고정된 정책 경계 안에서 모델의 자율 선택을 허용하는 방식.

</details>

| 조정 방식 | 워크플로형 | 자율 라우팅형 | 혼합형 |
|:---|:---|:---|:---|
| 적용 기준 | 고정 절차•승인 업무 처리 | 사전 정의가 어려운 경로 | 통제•유연성 동시 요구 |
| 핵심 특징 | 명시적 그래프•**상태 전이** 제어 | 모델의 역할•도구 선택 | 고정 경계 내 자율 선택 |
| 한계 | 변화 대응 경직성 | 목표 이탈•재현성 저하 | 설계•관측 복잡성 |

> 요약: 통제는 **워크플로형**, 유연성은 **자율 라우팅형**, 절충은 혼합형

#### 한줄 요약

- 복잡 자동화는 **워크플로**•**체크포인트** 기반 실패 재개

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **멱등키(Idempotency Key)**: 재시도 요청이 이미 처리되었는지 식별하여 중복 실행을 막는 값이다.
- **결정적 재개(Deterministic Resume)**: 입력•결과•정책 버전을 복원하여 같은 실패 지점 이후를 예측 가능하게 이어가는 방식.
- **승인 재검증(Approval Re-validation)**: 승인 대기 중 상태 변화를 반영하기 위해 실행 직전에 대상•금액•권한을 다시 확인하는 절차.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 재시도에 따른 중복 부작용 | **멱등키**와 실행 결과를 체크포인트에 저장 | 결제•전송의 중복 실행 방지 |
| 자율 분기의 목표 이탈 | 허용 경로•도구•예산•반복 수 강제 | 탐색 범위와 실행 비용 통제 |
| 승인 대기 중 상태 변경 | **승인 재검증**으로 대상•금액•권한 확인 | 오래된 승인에 따른 오실행 차단 |
| 장애 시 복구 지점 불명확 | 입력•결과•정책 버전의 단계별 추적 | 실패 지점부터 **결정적 재개** |

#### 한줄 요약

- 환불•변경은 **상태 재검증•HITL 승인** 후 실행

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **워크플로형 선택 기준(Workflow Selection Criteria)**: 고정 절차와 승인•감사 요구가 강할 때 명시적 실행 경로를 선택하는 기준이다.
- **혼합형 선택 기준(Hybrid Selection Criteria)**: 경로의 불확실성을 수용하되 권한•비용•승인 경계는 고정해야 할 때 적용하는 기준이다.

</details>

- 고정 절차•승인은 **워크플로형**, 불확실 경로는 **혼합형**

#### 한줄 요약

- **경로 불확실성•비가역성**에 따라 조정 방식 결정
