## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **에이전트 오케스트레이션(Agent Orchestration)**: 목표 달성을 위해 에이전트•도구의 실행 경로와 상태•정책•복구를 통합 조정하는 관리 계층이다.
- **워크플로**: 작업 순서와 조건 분기, 반복, 완료 상태를 명시한 실행 절차다.

</details>

- 정의/개념: 에이전트•도구의 경로•상태•정책•복구를 조정하는 **관리 계층**
- 배경/필요성: 임의 호출 연결로는 실패 후 **실행 분기 재현•상태 복구 불가**

#### 한줄 요약

- **실행 경로•상태•승인•복구**를 통합 조정

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **워크플로 그래프(Workflow Graph)**: 작업을 노드로, 실행 순서와 조건 분기를 전이로 표현한 구조다.
- **라우터(Router)**: 현재 상태와 정책을 평가하여 다음 실행 경로를 선택하는 구성요소다.
- **체크포인트(Checkpoint)**: 실패나 중단 뒤 이어서 실행할 수 있도록 단계 상태를 저장한 지점이다.

</details>

- **워크플로 그래프**로 순차•조건•반복 경로 정의
- **라우터**로 상태에 따른 실행 경로 선택
- **체크포인트**로 실패 지점부터 재개
- **통제 축**: 권한•승인•비용•오류 단계별 관리

#### 한줄 요약

- **워크플로•체크포인트•승인 지점**을 사전 정의

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 실행 전에 사람이 근거와 영향을 검토하고 승인 여부를 결정하는 통제 방식이다.
- **스케줄러(Scheduler)**: 의존성과 가용 능력에 따라 실행 시점을 배정하는 구성요소다.
- **상태 저장소(State Store)**: 단계별 입력•결과•승인•오류를 보존하는 구성요소다.
- **관측성(Observability)**: 추적•로그•지표를 통해 워크플로 내부 상태와 변화를 파악하는 능력이다.
- **추적 식별자(Trace Identifier, Trace ID)**: 여러 단계의 호출과 결과를 하나의 실행 흐름으로 연결하는 식별자다.

</details>

- 정책•승인 계층은 **HITL** 통제를 적용하고 관측•감사 계층은 **Trace ID** 기반으로 실행 흐름을 연결한다.

```text
                       [워크플로 그래프]
                    /           |           \
       [라우터•스케줄러] [상태•체크포인트] [정책•승인]
                    \           |           /
                         [관측•감사]
```

선의 의미: 워크플로 그래프는 라우터•스케줄러, 상태•체크포인트, 정책•승인의 실행 경계를 정의하고, 관측•감사는 세 영역의 상태와 결정 근거를 공통으로 추적한다.

| 구성요소 | 책임 |
|:---|:---|
| 워크플로 그래프 | 작업 노드와 **조건 전이** 정의 |
| 라우터•스케줄러 | 상태•의존성으로 **다음 실행** 결정 |
| 상태•체크포인트 | 단계 상태의 **저장•복구** |
| 정책•승인 | **HITL•권한•예산** 강제 |
| 관측•감사 | **관측성•Trace ID** 기반 상태 추적 |

#### 한줄 요약

- **라우터•상태•정책•관측 계층**이 실행 경로 통제

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **멱등성(Idempotency)**: 같은 작업을 재실행해도 결제•전송 같은 부작용이 중복되지 않는 성질이다.
- **상태 전이**: 실행 결과와 조건에 따라 워크플로의 현재 단계를 다음 단계로 변경하는 과정이다.

</details>

```text
오케스트레이터
   │ 1. 체크포인트 상태 복원
   ├──────────────────────┐
   │ 종료 상태 전까지     │
   └──────────┬───────────┘
   ▼
정책 엔진
   │ 2. 권한•예산•승인 판정
   │ 3. 실행 경로 허용
   ▼
오케스트레이터
   │ 4. 멱등키 기반 작업 실행
   ▼
에이전트•도구
   │ 실행 결과•오류 반환
   ▼
오케스트레이터
   │ 5. 결과 저장•상태 전이
   ▼
상태 저장소
```

1. **체크포인트 상태 복원**: 중단 지점의 입력•결과•**실행 상태** 재구성
2. **권한•예산•승인 판정**: 현재 노드의 **정책 조건** 평가
3. **실행 경로 허용**: 상태와 조건에 맞는 **다음 노드** 선택
4. **멱등키 기반 작업 실행**: 재시도 시 **중복 부작용** 방지
5. **결과 저장•상태 전이**: 실행 기록을 남기고 **후속 경로** 결정

#### 한줄 요약

- **체크포인트 복원•정책 판정** 후 결과와 상태 저장

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **워크플로형**: 사전에 정의한 그래프와 상태 전이에 따라 실행을 통제하는 조정 방식이다.
- **자율 라우팅형**: 모델이 관찰 결과에 따라 역할이나 도구와 다음 경로를 선택하는 방식이다.
- **혼합형**: 고정된 정책 경계 안에서 모델의 자율 선택을 허용하는 방식이다.

</details>

| 조정 방식 | 워크플로형 | 자율 라우팅형 | 혼합형 |
|:---|:---|:---|:---|
| 적용 기준 | **고정 절차•승인 업무** | **사전 정의가 어려운 경로** | **통제•유연성 동시 요구** |
| 핵심 특징 | **명시적 그래프•상태 전이** | 모델의 **역할•도구 선택** | **고정 경계 내 자율 선택** |
| 한계 | **변화 대응 경직** | **목표 이탈•재현성 저하** | **설계•관측 복잡** |

> 요약: 통제에는 **워크플로형**, 유연성에는 **자율형**, 절충에는 **혼합형** 적용

#### 한줄 요약

- 복잡 자동화는 **워크플로•체크포인트**로 실패 지점 재개

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **멱등키**: 재시도 요청이 이미 처리되었는지 식별하여 중복 실행을 막는 값이다.
- **결정적 재개**: 입력•결과•정책 버전을 복원하여 같은 실패 지점 이후를 예측 가능하게 이어가는 방식이다.
- **승인 재검증**: 승인 대기 중 상태 변화를 반영하기 위해 실행 직전에 대상•금액•권한을 다시 확인하는 절차다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 재시도에 따른 **중복 부작용** | **멱등키•실행 결과**를 체크포인트에 저장 | 결제•전송의 **중복 실행** 방지 |
| 자율 분기의 **목표 이탈** | **허용 경로•도구•예산•반복 수** 강제 | 탐색 범위와 **실행 비용** 통제 |
| 승인 대기 중 **상태 변경** | 승인 직전 **대상•금액•권한** 재검증 | 오래된 승인에 따른 **오실행** 차단 |
| 장애 시 **복구 지점** 불명확 | **입력•결과•정책 버전**을 단계별 추적 | 실패 지점부터 **결정적 재개** |

#### 한줄 요약

- 환불 변경은 **실행 직전 상태 재검증•HITL 승인** 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **워크플로형 선택 기준**: 고정 절차와 승인•감사 요구가 강할 때 명시적 실행 경로를 선택한다.
- **혼합형 선택 기준**: 경로의 불확실성을 수용하되 권한•비용•승인 경계는 고정해야 할 때 선택한다.

</details>

- 고정 절차•승인은 **워크플로형**, 불확실 경로는 **혼합형** 선택

#### 한줄 요약

- 비가역 단계가 많을수록 **체크포인트•승인 규칙** 강화
