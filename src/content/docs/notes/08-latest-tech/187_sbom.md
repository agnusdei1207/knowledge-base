## 미리 알고가기

- **SBOM(에스봄)**: Software Bill of Materials의 머리글자로, 소프트웨어 구성요소·버전·관계를 기록한 명세서
- **VEX(벡스)**: Vulnerability Exploitability eXchange의 약자로, 특정 취약점의 제품 영향 여부와 조치 상태를 전달
- **SPDX(에스피디엑스)·CycloneDX(사이클론디엑스)**: 기계가 판독할 수 있는 대표 SBOM 표준 형식



## Ⅰ. 개요

- 정의/개념: 소프트웨어 제품의 구성요소·버전·식별자·의존 관계를 구조화한 명세서다
- 기존 한계: 제품에 포함된 직접·전이 의존성을 알 수 없으면 취약점과 라이선스 영향 범위를 신속히 찾기 어렵다
- 기존 한계: 완성된 소프트웨어만으로는 포함된 오픈소스·라이브러리 버전을 알 수 없어 취약점 영향 제품과 대응 우선순위를 신속히 식별하기 어렵다.
### 쉽게 이해하기 (학습용)

- 제품의 구성 목록을 검색해 취약점·라이선스 영향 범위를 빠르게 확인한다.

## Ⅱ. 특징

- 식별자·버전·관계로 직접·전이 구성요소를 추적한다
- 표준 형식으로 생성·교환하고 제품 아티팩트와 결속한다
- 구성 목록은 안전성을 보장하지 않아 VEX·서명·출처와 연계한다

### 쉽게 이해하기 (학습용)

- 성분표만으로 안전성과 포장 무결성을 보장할 수 없듯 SBOM도 다른 증거와 함께 사용한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[제품 아티팩트] ← 해시 결속 → [SBOM]
                              ├→ [취약점 DB]
                              ├→ [VEX]
                              └→ [자산·조치 관리]
```

| 설계 요소 | 설명 |
|:---|:---|
| 대상식별 | 제품명·버전·배포 단위 연결 |
| 구성요소 | 식별자·버전·해시·라이선스 정보 |
| 관계·범위 | 직접·전이 의존성 관계 및 누락 표시 |
| 작성정보 | 도구·작성자·시간·표준 버전 |
| 증거결합 | 서명·해시·빌드 출처와 연결 |
| 취약점·VEX | 취약점 매핑 및 영향 범위 관리 |

> 요약: 구성 목록을 제품 해시·VEX·출처 증거와 결합한다

### 쉽게 이해하기 (학습용)

- 제품 번호에 성분표·제조 기록·봉인을 연결해 보관하는 구조와 같다.

## Ⅳ. 원리 및 절차 흐름도

```text
SBOM생성
   ↓
정보검증
   ↓
서명결합
   ↓
자산관리
   ↓
취약점평가
```

| 절차 | 설명 |
|:---|:---|
| 1. SBOM 생성 | 빌드 결과의 구성요소·관계 추출 |
| 2. 정보 검증 | 형식·식별자·완전성과 누락 확인 |
| 3. 아티팩트 결속 | 해시·서명·출처와 SBOM 연결 |
| 4. 자산 매핑 | 배포 제품·버전에 SBOM 연결 |
| 5. 영향 평가 | 취약점·VEX 확인 후 조치 |

> 요약: 빌드 SBOM을 자산·취약점 조치에 연결

### 쉽게 이해하기 (학습용)

- 빌드 때 명세를 만들고 제품 해시와 결속한 뒤 배포 자산과 연결해 영향 제품만 조치한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | SBOM | VEX | Provenance·전자서명 |
|:---|:---|:---|:---|
| 적용 기준 | 구성요소·의존성 식별 | 취약점 영향 상태 전달 | 빌드 출처·변조 여부 검증 |
| 핵심 특징 | 제품별 구성 인벤토리 | 영향 여부·근거·조치 기록 | 빌더 신원과 다이제스트 결속 |
| 한계 | 누락·제품 오결속 가능 | 판단 오류·상태 노후화 | 구성 완전성과 안전성 미보장 |

> 요약: SBOM·VEX·provenance의 증명 범위 구분

### 쉽게 이해하기 (학습용)

- SBOM은 구성, VEX는 취약점 영향, 출처·서명은 생성 과정과 변조 여부를 설명한다.

## Ⅵ. 실무 사례

1. 보안팀은 Log4Shell 공지 시 SBOM의 패키지 URL·버전·의존 관계로 영향받는 서비스를 식별한다.

### 쉽게 이해하기 (학습용)

- 취약점 정보와 구성요소 식별자를 대조하면 패치가 필요한 제품을 빠르게 좁힐 수 있다.

## Ⅶ. 결론

- 소프트웨어 구성요소의 취약점 영향을 신속히 추적하기 위해 제품 결속·완전성·최신성을 검토하여 SBOM을 운영해야 한다.

### 쉽게 이해하기 (학습용)

- SBOM은 안전 인증서가 아니라 실제 제품 구성을 추적하는 최신 목록이다.
