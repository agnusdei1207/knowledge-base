## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **소프트웨어 자재명세서(Software Bill of Materials, SBOM)**: 소프트웨어 구성요소•버전•의존 관계를 기록한 기계 판독 명세서을 말한다.
- **전이 의존성(Transitive Dependency)**: 직접 사용한 구성요소가 다시 참조해 제품에 간접 포함되는 의존성을 의미한다.

</details>

- 정의/개념: 소프트웨어 구성요소•버전•의존 관계를 기록한 **SBOM**임.
- 배경/필요성: 완성 제품만으로는 직접•전이 의존성의 **취약점•라이선스 영향** 식별하기 어렵음.
#### 한줄 요약

- 제품의 구성 목록을 검색해 취약점•라이선스 영향 범위를 빠르게 확인한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **소프트웨어 패키지 데이터 교환(Software Package Data Exchange, SPDX)**: 구성요소와 관계의 기계 판독•교환을 위한 SBOM 표준 형식로 정의된다.
- **CycloneDX**: 보안 사용 사례와 구성요소 관계를 표현하는 SBOM 표준 형식을 말한다.
- **취약점 악용 가능성 교환(Vulnerability Exploitability eXchange, VEX)**: 특정 취약점의 제품 영향 여부와 조치 상태를 전달하는 문서을 의미한다.

</details>

- 식별자•버전•관계 기반 **직접•전이 구성요소 추적**이 핵심임.
- **SPDX**•**CycloneDX** 기반 **기계 판독•자동 교환**이 핵심임.
- 제품 해시•서명으로 **배포본 결속**, VEX로 **영향 판정**이 핵심임.
#### 한줄 요약

- SBOM과 제품 결속•취약점 영향 증거의 결합을 검증한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **패키지 URL(Package URL, purl)**: 패키지 유형•이름•버전 등을 나타내는 표준 구성요소 식별자이다.
- **아티팩트 결속**: SBOM을 제품 해시•서명과 연결해 어떤 배포본의 명세인지 증명하는 관계로 정의된다.
- **대상 제품•구성요소**: 명세가 설명하는 배포물과 그 안에 포함된 패키지•라이브러리•파일을 말한다.
- **의존 관계**: 구성요소 사이의 포함•직접•전이 의존성을 표현한 연결 정보이다.

</details>

**VEX**는 구성요소별 영향•조치 상태를 관리한다.

```text
                  [대상 제품]
                      |
                [구성요소 식별]
                      |
                  [의존 관계]
                      |
                [작성•결속 정보]
                      |
                 [취약점•VEX]
```

선의 의미: 대상 제품에 구성요소 식별과 의존 관계가 결속되고, 작성•결속 정보와 취약점•VEX가 명세의 진위 및 영향 상태를 연결한다.

| 구성요소 | 책임 |
|:---|:---|
| 대상 제품 | 제품명•버전•배포 단위의 **SBOM 연결** |
| 구성요소 식별 | purl•버전과 **해시•라이선스 기록** |
| 의존 관계 | 직접•전이 **포함•의존 관계 표현** |
| 작성•결속 정보 | 도구•시간•표준과 **제품 해시•서명 결속** |
| 취약점•VEX | 취약점 매핑과 **영향•조치 상태 관리** |

#### 한줄 요약

- 제품•구성요소•의존 관계를 작성•결속•영향 정보와 연결한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **출처 증명(Provenance)**: 아티팩트가 어떤 소스•빌더•입력으로 생성됐는지 기록한 증거로 정의된다.
- **영향 상태**: 취약점이 특정 제품 구성에서 악용 가능한지와 패치•완화•예외 조치가 어떤 상태인지 나타낸 정보로 정의된다.

</details>

**SBOM**•**VEX**를 빌드•배포 자산에 연결한다.

```text
[빌드 시스템]
      │ 1. 구성요소•관계
      ▼
[SBOM 생성기]
      │ 2. 결속 SBOM
      ▼
[제품•자산 관리]
      │ 3. 배포 구성정보
      ▼
[취약점•VEX]
      │ 4. 영향 상태
      ▼
[조치 담당] ── 조치 결과 ──▶ [제품•자산 관리]
```

### 동작 원리

1. **구성요소**•**관계**: 직접•전이 의존성과 식별자 추출
2. **결속 SBOM**: 검증 후 제품 해시•서명•출처와 연결
3. **배포 구성정보**: 제품별 SBOM을 실제 배포 자산에 매핑
4. **영향 상태**: 취약점•VEX로 영향•조치 상태 판정

#### 한줄 요약

- 빌드 때 명세를 만들고 제품 해시와 결속한 뒤 배포 자산과 연결해 영향 제품만 조치한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전자서명**: 개인키로 아티팩트 다이제스트에 서명해 서명자와 변조 여부를 검증하는 수단이다.
- **구성 인벤토리**: 제품별 포함 구성요소•버전•관계를 검색할 수 있도록 관리한 목록이다.

</details>

SBOM은 구성, VEX는 영향 상태, 출처 증명은 생성 과정을 설명한다.

| 판단 기준 | SBOM | VEX | 출처 증명•전자서명 |
|:---|:---|:---|:---|
| 적용 기준 | **구성요소•의존성 식별** | 취약점의 **영향 상태 전달** | **빌드 출처•변조 여부** 검증 |
| 핵심 특징 | 제품별 **구성 인벤토리** | **영향 여부•조치 상태** 기록 | 빌더 신원과 **다이제스트 결속** |
| 한계 | **구성 누락•제품 오결속**가능 | **판단 오류•상태 노후화** | **구성 완전성•안전성** 미보장 |

#### 한줄 요약

- SBOM은 구성, VEX는 취약점 영향, 출처•서명은 생성 과정과 변조 여부를 설명한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **완전성**: 실제 제품의 직접•전이•동적 구성요소가 SBOM에 빠짐없이 기록된 정도을 의미한다.
- **최신성**: 제품•구성•취약점•VEX 변경이 현재 SBOM과 영향 판정에 반영된 정도을 의미한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 완전성** 미검증 시 전이•동적 구성의 **누락 | 다단계 생성•누락 표시와 **정확도 검증** | SBOM **누락률** 감소 |
| 제품 결속** 미검증 시 SBOM과 배포본의 **버전 불일치 | 해시•서명•출처 기반 **아티팩트 결속** | SBOM•배포본 **동일성** 확보 |
| 최신성** 미검증 시 취약점•VEX 상태의 **노후화 | 자산 연계•재평가와 **수명주기 갱신** | 취약점 판단 **최신성** 유지 |

#### 한줄 요약

- 구성요소 목록의 완전성과 제품 결속을 검증하고 취약점•VEX 변경에 따라 영향 자산을 지속 재평가한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **취약점 영향 판정**: 구성 목록과 VEX•실행 조건을 결합해 실제 조치가 필요한 제품을 식별하는 과정을 의미한다.
- **배포 자산 매핑**: 제품 버전별 SBOM을 실제 운영 중인 시스템과 인스턴스에 연결하는 활동로 정의된다.

</details>

- 구성요소는 **SBOM**으로 식별하고 **배포 자산 매핑•VEX 영향 판정**으로 조치 대상을 결정함.

#### 한줄 요약

- **완전성•제품 결속•최신성**을 검증한 SBOM으로 조치 대상 결정
