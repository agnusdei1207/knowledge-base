## 미리 알고가기

- **피처 저장소(Feature Store)**: 학습·추론에 동일한 피처 정의와 시점 기준을 재사용하도록 저장·제공하는 데이터 인프라
- **핵심 목적**: train-serve skew 축소, 피처 중복 개발 및 불일치 제거
- **저장소**: Offline store와 Online store 운영 구조가 일반적

## Ⅰ. 개요

- 정의/개념: 학습·추론 피처를 정의·저장·제공하는 플랫폼이다
- 기존 한계: 학습과 서빙 파이프라인이 피처를 따로 계산하면 시점 누출과 변환 로직 차이로 값이 불일치한다.

### 쉽게 이해하기 (학습용)
- 학습에는 당시의 과거 값을, 추론에는 최신 값을 같은 정의로 제공하는 피처 창고다.

## Ⅱ. 특징

- 정의·엔터티·원천 버전 기반 **피처 계보**
- 오프라인 저장소의 **시점 정합 학습셋**
- 온라인 저장소의 **저지연 제공·동기화**

### 쉽게 이해하기 (학습용)

- 학습 시점에 알 수 있었던 값만 쓰고 같은 계산 규칙의 최신 값을 실시간 추론에 제공한다.

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 레지스트리 | 정의 및 버전 정보 관리 |
| Offline Store | 시계열 과거 데이터 저장 |
| 처리 엔진 | 최신 데이터 동기화 |
| Online Store | 저지연 최신 데이터 저장 |
| 피처 서버 | 엔터티 기반 추론값 반환 |

> 요약: 정의를 기준으로 과거·최신 저장소와 서버를 연결한다

### 쉽게 이해하기 (학습용)

- 레지스트리가 계산 규칙을 정하고 과거 창고와 최신 창구 및 피처 서버가 같은 정의를 사용한다.

## Ⅳ. 원리 및 절차 흐름도

```text
정의 등록 → 과거 피처 수집
                ├─ 학습 요청 → 시점 정합 조인 → 학습셋 반환
                └─ 최신값 갱신 → Online Store
                                     ↓
                                엔터티 조회
```

| 절차 | 설명 |
|:---|:---|
| 정의 등록 | 규칙 및 엔터티 관리 |
| 과거 조회 | 과거 시계열 값 추출 |
| 시점 정합 | 미래 정보 누출 방지 |
| 최신값 반영 | 데이터 동기화 수행 |
| 온라인 조회 | 엔터티 기반 저지연 반환 |

> 요약: 과거 값은 시점 조인하고 최신 값은 동기화한다

### 쉽게 이해하기 (학습용)

- 학습셋은 예측 당시 알 수 있던 값만 조인하고 실시간 추론은 동기화된 최신 값을 조회한다.

## Ⅴ. 피처 저장소 유형 비교

| 구분 | 오프라인 저장소 | 온라인 저장소 |
|:---|:---|:---|
| 보유 범위 | 시계열 과거값 | 엔터티별 최신값 |
| 조회 방식 | 시점 정합 조회 | 엔터티 키 조회 |
| 적용 기준 | 학습셋, 배치 추론 | 실시간 추론 |
| 핵심 특징 | 대용량 시점 기반 피처 조회 | 최신 피처 저지연 키 조회 |
| 한계 | 갱신 지연·시점 조인 비용 | 저장 비용·일관성 관리 |

> 요약: 과거 학습은 오프라인, 실시간 추론은 온라인을 쓴다

### 쉽게 이해하기 (학습용)

- 오프라인 저장소는 과거 기록으로 학습셋을 만들고 온라인 저장소는 현재 값을 빠르게 제공한다.

## Ⅵ. 실무 사례
1. 사기 탐지에 **시점 정합 학습 피처와 온라인 최신 피처**를 제공한다

### 쉽게 이해하기 (학습용)

- 결제 이전 값으로 학습해 미래 정보 누수를 막고 추론에는 같은 정의의 최신 값을 제공한다.

## Ⅶ. 결론
- 학습·추론 피처 불일치를 방지하기 위해 **정의 버전·시점 정합성·온라인 지연·동기화 신선도**를 검토하고, 공통 레지스트리와 오프라인·온라인 저장소를 운영한다.

### 쉽게 이해하기 (학습용)

- 학습과 추론의 피처 정의·시점·동기화 지연을 함께 관리해야 같은 의미의 값을 제공할 수 있다.
