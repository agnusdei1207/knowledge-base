## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **C2PA**: 콘텐츠 출처와 편집 이력을 서명된 매니페스트로 교환·검증하는 개방형 표준이다.
- **서명 매니페스트**: 출처 진술·클레임·서명과 콘텐츠 연결 정보를 함께 담아 무결성을 검증하는 구조이다.

</details>

- 정의/개념: **C2PA**는 콘텐츠의 생성·편집 도구와 이력을 서명 매니페스트로 연결해 출처 진술을 교환·검증하는 콘텐츠 출처 표준
- 배경/필요성: 일반 메타데이터의 **편집 이력·변조 검증** 한계

#### 한줄 요약

- 카메라·편집기·플랫폼이 같은 형식의 봉인된 작업 장부를 이어 쓰게 한 공통 규칙이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상호운용 출처성**: 공통 형식으로 도구와 플랫폼 사이의 콘텐츠 출처 이력을 이어 검증하는 성질이다.
- **하드 바인딩**: 해시 등으로 매니페스트와 콘텐츠를 강하게 연결해 변경을 탐지하는 방식이다.
- **소프트 바인딩**: 지문·워터마크 등으로 분리된 매니페스트를 외부 저장소에서 다시 찾는 방식이다.

</details>

- **상호운용 출처성**: 공통 형식으로 도구 간 출처 이력 단절을 줄이고 발행 경로를 검증
- **이중 바인딩성**: 하드 바인딩으로 변경을 탐지하고 소프트 바인딩으로 제거된 매니페스트의 재발견 지원
- **진위 한계성**: 유효 서명은 발행 경로만 보장하므로 워터마크·합성 탐지로 출처 이력 공백 보완

#### 한줄 요약

- 장부의 봉인과 발행자는 확인할 수 있지만 기록한 내용이 사실인지는 별도로 검증해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **진술**: 콘텐츠의 생성·편집·도구·구성 자산에 관한 출처 기록이다.
- **클레임**: 진술 참조와 콘텐츠 바인딩을 묶어 서명 대상으로 만든 구조이다.
- **신뢰 경로**: 서명 자격증명에서 신뢰한 발행 주체까지 이어지는 검증 관계이다.

</details>

```mermaid
block-beta
  columns 3
  assertion["진술 저장소"]
  claim["클레임 구성기"]
  signer["서명·자격증명부"]
  manifest["매니페스트 저장소"]
  verifier["매니페스트 검증기"]
  assertion --- claim
  claim --- signer
  signer --- manifest
  manifest --- verifier
```

| 구성요소 | 책임 |
|:---|:---|
| **진술 저장소** | 생성·편집 이력 진술 보관 |
| **클레임 구성기** | 진술 참조·콘텐츠 바인딩 결합 |
| **서명·자격증명부** | 클레임 무결성·신뢰 경로 입증 |
| **매니페스트 저장소** | 매니페스트·참조 관계 보관 |
| **매니페스트 검증기** | 구조·서명·폐기 상태 판정 |

#### 한줄 요약

- 작업 기록과 원본 지문을 함께 봉인하고 검증기가 봉인·발행 경로·유효 기간을 확인한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **내장 매니페스트**: 콘텐츠 파일 내부에 함께 저장해 배포하는 출처 기록이다.
- **원격 매니페스트**: 콘텐츠와 분리된 외부 위치에 저장하고 참조로 연결하는 출처 기록이다.
- **폐기 상태**: 서명 키나 자격증명이 더 이상 유효하지 않은지를 나타내는 검증 결과이다.

</details>

```mermaid
sequenceDiagram
  participant A as 진술 저장소
  participant C as 클레임 구성기
  participant S as 서명·자격증명부
  participant M as 매니페스트 저장소
  participant V as 매니페스트 검증기
  A->>C: 1. 생성·편집 진술
  C->>S: 2. 진술 참조·콘텐츠 바인딩
  S->>M: 3. 서명 클레임·자격증명
  M->>V: 4. 내장·원격 매니페스트
  V-->>M: 5. 서명·바인딩·폐기 상태
```

1. **생성·편집 진술**: 출처 이력과 구성 자산 기록
2. **진술 참조·콘텐츠 바인딩**: 클레임과 자산 변경 상태 연결
3. **서명 클레임·자격증명**: 발행 주체와 무결성 증명
4. **내장·원격 매니페스트**: 자산 배포와 이력 탐색 경로 제공
5. **서명·바인딩·폐기 상태**: 유효성과 내용 사실성을 분리 판정

#### 한줄 요약

- 작업 내역과 원본 지문을 봉인해 배포하고 수신자는 매니페스트의 봉인·지문·발행 경로를 확인한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **일반 메타데이터**: 장비·시간·위치 같은 속성을 기록하지만 서명 없이는 수정 가능한 정보이다.
- **파일 해시 공증**: 특정 시점의 파일 해시를 외부 기록에 남겨 존재와 동일성을 증명하는 방식이다.

</details>

| 판단 기준 | C2PA | 일반 메타데이터 | 파일 해시 공증 |
|:---|:---|:---|:---|
| **기록 대상** | 출처·편집 진술과 **구성 자산** | 장비·시간 등 **속성값** | 파일 해시와 **등록 시점** |
| **검증 근거** | 바인딩·서명·**신뢰 경로** | 서명 없이는 **수정 가능** | 외부 기록과 **해시 일치** |
| **적용 기준** | 도구 간 **출처 이력 연결** | 비보안 **속성 교환** | 파일의 **존재 시점** 증명 |

#### 한줄 요약

- C2PA는 편집 이력을 잇고 일반 메타데이터는 속성을 붙이며 해시 공증은 파일의 존재 시점을 남긴다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **매니페스트 제거**: 콘텐츠 변환·유통 과정에서 내장 출처 기록이 분리되거나 삭제되는 문제이다.
- **자격증명 폐기**: 서명 키가 노출되거나 신뢰를 잃어 발행 주체의 서명을 더 이상 인정할 수 없는 상태이다.
- **사실성 오인**: 유효 서명이 발행 경로만 입증하는데 콘텐츠 내용까지 사실이라고 잘못 해석하는 문제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **매니페스트 제거** | **소프트 바인딩·외부 저장소** 병행 | 출처 이력의 **재발견** |
| 서명 키·자격증명의 **폐기** | 신뢰 목록과 **폐기 상태** 검증 | 무효 **발행자 차단** |
| 유효 서명의 **사실성 오인** | 서명 상태와 **내용 검증** 분리 표시 | 출처·진실성의 **혼동 방지** |
| 버전별 **형식·자산 지원 차이** | **C2PA 2.4** 프로파일·상호운용 시험 | 버전 간 **검증 실패 방지** |

#### 한줄 요약

- 뉴스 사진은 촬영부터 편집까지 매니페스트를 이어 기사 뷰어에 검증 상태를 표시하고, 파일에서 빠진 매니페스트는 외부 보관소에서 복구한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **C2PA 2.4**: crJSON과 자산 형식·진술·검증 기능을 확대한 2026년 4월 규격이다.
- **내용 사실성**: 콘텐츠가 묘사하거나 주장하는 사건과 정보가 실제 사실과 일치하는 정도이다.

</details>

- 출처 이력은 **C2PA 2.4**로 연결하고 서명 검증과 **내용 사실성**은 분리 판정

#### 한줄 요약

- C2PA는 누가 기록을 봉인했는지 보여 주므로 서명 키·발행자와 매니페스트 복구 경로를 관리해야 한다.
