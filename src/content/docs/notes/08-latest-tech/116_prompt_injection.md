## 미리 알고가기

- **프롬프트 인젝션(Prompt Injection)**: 비신뢰 입력의 지시가 상위 업무 지침을 교란해 모델 행동을 바꾸는 공격
- **권한 브로커(Permission Broker)**: 모델의 도구 호출을 독립 정책으로 검사해 허용된 권한만 부여하는 통제
- **승인 게이트(Approval Gate)**: 정보 반출·메일 발송 등 고위험 행동을 실행 전에 사람이나 정책이 승인하는 경계



## Ⅰ. 개요

- 정의/개념: 비신뢰 지시로 **상위 지침·도구 행동**을 교란하는 공격
- 배경/필요성: 자연어의 **신뢰 지시·비신뢰 데이터** 구별 한계로 권한 오용 발생

### 쉽게 이해하기 (학습용)
- AI가 참고 자료의 문장을 운영자 명령으로 착각해 답변과 행동이 조종된다.

## Ⅱ. 특징

- 비신뢰 데이터의 **실행 지시 승격**
- 직접 입력·외부 콘텐츠의 **다중 유입 경로**
- 독립 권한 검증·최소 권한 기반 **도구 피해 제한**

### 쉽게 이해하기 (학습용)
- 문장 필터만 믿지 않고 모델이 제안한 행동을 별도 정책으로 다시 확인해야 한다.

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 1
  A["신뢰 채널"]
  B["비신뢰 컨텍스트"]
  C["권한 브로커"]
  D["승인 게이트"]
  E["격리·감사"]
  A --- B
  B --- C
  C --- D
  D --- E
```

| 구성요소 | 책임 |
| :--- | :--- |
| 신뢰 채널 | 외부 입력의 지시 승격 원천 차단 |
| 비신뢰 컨텍스트 | 최소 자료 전달과 지시·데이터 경계 유지 |
| 권한 브로커 | 도구별 허용 목록으로 권한 범위 제한 |
| 승인 게이트 | 독립 정책 검사 후 고위험 행동 승인 |
| 격리·감사 | 샌드박스 환경 실행 및 전체 기록 추적 |

> 요약: 입력을 불신하고 도구 행동을 별도 정책으로 통제한다

### 쉽게 이해하기 (학습용)
- 별도 문지기가 도구 권한과 대상을 확인하고 위험한 행동은 사람이 승인한다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant U as 사용자
    participant M as 모델
    participant B as 권한 브로커
    participant G as 승인 게이트
    participant T as 격리 도구
    U->>M: 1. 신뢰·비신뢰 입력 전달
    M->>B: 2. 구조화 행동 제안 전달
    B->>G: 3. 정책 통과 행동 전달
    G->>T: 4. 승인된 최소 권한 전달
    T-->>U: 5. 검사된 결과 반환
```

### 동작 원리

- **1. 신뢰·비신뢰 입력 전달**: 출처 라벨 기반 지시·데이터 경계 구성
- **2. 구조화 행동 제안 전달**: 자유 텍스트와 도구 인자 분리
- **3. 정책 통과 행동 전달**: 사용자 목적·도구·대상 권한 독립 검증
- **4. 승인된 최소 권한 전달**: 비가역 행동 승인과 격리 실행
- **5. 검사된 결과 반환**: 민감정보 반출 검사와 감사 기록 보존

> 요약: 출처 분류 뒤 정책·승인을 거쳐 최소 권한으로 실행한다

### 쉽게 이해하기 (학습용)
- 모델의 행동 제안을 제한한 뒤 독립 정책 검사와 사람 승인을 거쳐 실행한다.

## Ⅴ. 종류 및 비교

| 공격 경로 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 |
| :--- | :--- | :--- |
| 적용 기준 | 정책을 덮어쓰는지 검증할 때 적용 | 콘텐츠 속 지시 수행 여부를 검증할 때 적용 |
| 핵심 특징 | 대화 입력에 공격 지시 제출 | 외부 콘텐츠가 공격 지시 전달 |
| 한계 | 표현 변형 우회 | 지연 발동·출처 확산 |

> 요약: 직접은 대화, 간접은 외부 콘텐츠로 지시를 주입한다

### 쉽게 이해하기 (학습용)
- 직접 공격은 대화창에 명령을 넣고 간접 공격은 문서·메일 같은 정보에 명령을 숨긴다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 비신뢰 문장이 **상위 지시**로 승격 | 출처 라벨·지시/데이터 경계 분리 | **지시 우선순위** 보존 |
| 모델 계획이 **도구 권한** 직접 행사 | 권한 브로커·승인 게이트 적용 | 인젝션의 **행동 피해** 제한 |

### 쉽게 이해하기 (학습용)

- 메일 속 숨은 명령이 있어도 요약 모델이 직접 발송하지 못하게 도구 권한을 분리한다.

## Ⅶ. 결론

- **입력 신뢰도·도구 권한**으로 프롬프트 인젝션의 실행 영향을 격리

### 쉽게 이해하기 (학습용)
- 악성 문장을 모두 찾기보다 AI가 속아도 중요 정보와 도구를 못 쓰게 여러 통제를 둔다.
