## 미리 알고가기

- **프롬프트 인젝션**: 문서·질문에 숨긴 명령으로 AI가 지시 무시 후 공격자 의도대로 행동함
- **실제 피해**: 메일 발송·파일 읽기 등 권한 악용 시 정보 유출이나 오작업 발생
- **방어 원칙**: 모든 입력을 불신하고 AI 권한 최소화 및 명령·참고 자료 분리 필요



## Ⅰ. 개요

- **정의/개념**: 악성 텍스트로 모델 지시·행동을 바꾸는 공격이다
- **배경/필요성**: 지시·데이터 혼동에 따른 유출·오작업을 막는다

### 쉽게 이해하기 (학습용)
- AI가 참고 자료의 문장을 운영자 명령으로 착각해 답변과 행동이 조종된다.

## Ⅱ. 특징

- 자연어의 지시·데이터 경계가 약해 공격이 성립한다
- 직접·간접 유입 경로는 공격면을 넓힌다
- 패턴 필터만으로 의미를 바꾼 우회를 막기 어렵다
- 도구 권한은 모델 오판을 유출·변경 피해로 키운다
- 독립 검증·최소 권한은 공격의 실제 피해를 줄인다

### 쉽게 이해하기 (학습용)
- 문장 필터만 믿지 않고 모델이 제안한 행동을 별도 정책으로 다시 확인해야 한다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
| :--- | :--- |
| 신뢰 채널 | 외부 입력의 지시 승격 원천 차단 |
| 컨텍스트 | 최소 자료 전달 및 구분자 정화 활용 |
| 권한 브로커 | 도구별 허용 목록으로 권한 범위 제한 |
| 승인 게이트 | 독립 정책 검사 후 고위험 행동 승인 |
| 격리·감사 | 샌드박스 환경 실행 및 전체 기록 추적 |

> 요약: 입력을 불신하고 도구 행동을 별도 정책으로 통제한다

### 쉽게 이해하기 (학습용)
- 별도 문지기가 도구 권한과 대상을 확인하고 위험한 행동은 사람이 승인한다.

## Ⅳ. 원리 및 절차 흐름도

```text
출처 분류 → 컨텍스트 최소화 → 행동 제안
           ↓
정책 검증 → 사람 승인 → 최소 권한 실행
           ↓
        출력·감사
```

| 절차 | 설명 |
| :--- | :--- |
| 출처 분류 | 외부 콘텐츠를 데이터로만 취급 |
| 컨텍스트 최소화 | 비밀·불필요 지시 제거 |
| 행동 제안 | 구조화된 도구 인자만 생성 |
| 정책 검증 | 권한 및 도구 범위 검사 |
| 사람 승인 | 비가역 행동은 직접 승인 |
| 권한 실행 | 승인된 작업만 격리 실행 |

> 요약: 출처 분류 뒤 정책·승인을 거쳐 최소 권한으로 실행한다

### 쉽게 이해하기 (학습용)
- 모델의 행동 제안을 제한한 뒤 독립 정책 검사와 사람 승인을 거쳐 실행한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 |
| :--- | :--- | :--- |
| 유입 경로 | API에 악성 지시를 직접 제출함 | 문서·메일·도구 출력에 지시를 숨김 |
| 적용 기준 | 정책을 덮어쓰는지 검증할 때 적용 | 콘텐츠 속 지시 수행 여부를 검증할 때 적용 |
| 주요 위험 | 정책 우회·비밀 노출·미허용 도구 요청 | 권한 도용을 통한 정보 유출·오염 유발 |

> 요약: 직접은 대화, 간접은 외부 콘텐츠로 지시를 주입한다

### 쉽게 이해하기 (학습용)
- 직접 공격은 대화창에 명령을 넣고 간접 공격은 문서·메일 같은 정보에 명령을 숨긴다.

## Ⅵ. 실무 사례

1. 메일 요약 에이전트의 발송 권한을 분리한다
2. 고객 채팅의 규칙 무시 요청을 정책으로 거부한다

### 쉽게 이해하기 (학습용)

- 메일 속 숨은 명령이 있어도 요약 모델이 직접 발송하지 못하게 도구 권한을 분리한다.
- 채팅의 규칙 무시 요청이 모델을 속여도 별도 정책이 금지 행동을 거부한다.

## Ⅶ. 결론

- 비신뢰 입력과 도구 권한을 분리해 행동을 검증한다.

### 쉽게 이해하기 (학습용)
- 악성 문장을 모두 찾기보다 AI가 속아도 중요 정보와 도구를 못 쓰게 여러 통제를 둔다.
