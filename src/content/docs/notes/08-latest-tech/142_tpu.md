## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **텐서 처리장치(Tensor Processing Unit, TPU)**: Google이 신경망 텐서 연산용으로 설계한 전용 프로세서이다.
- **행렬 곱셈장치(Matrix Multiply Unit, MXU)**: 시스톨릭 배열로 행렬 곱을 수행하는 TPU 핵심 연산기이다.
- **주문형 집적회로(Application-Specific Integrated Circuit, ASIC)**: 특정 용도의 연산 구조를 고정한 전용 집적회로이다.

</details>

- 정의: 시스톨릭 MXU로 텐서를 처리하는 **AI 전용 ASIC**
- 배경/필요성: 범용 GPU는 다양한 그래픽 및 부동소수점 워크로드를 지원하기 위해 복잡한 워프 스케줄러, 레지스터 파일, 캐시 계층을 유지하므로 딥러닝의 핵심인 순수 2D 행렬 곱셈(Matrix Multiplication) 시 막대한 전력 소비와 레지스터 파일 접근 병목을 유발함에 따라, 구글이 대규모 신경망 훈련 및 추론 전용으로 개발한 2차원 시스톨릭 배열 기반의 주문형 반도체 TPU(Tensor Processing Unit: TPU v1~v5p/v6 / 2D Systolic Array Matrix Multiply Unit: MXU, XLA Compiler Graph Optimization, High-Speed Optical Interconnect: ICI, Bfloat16/FP8 Arithmetic) 아키텍처를 도입하여 **연산기 간 데이터를 박동(Systolic)처럼 직접 전달함으로써 레지스터 파일 읽기/쓰기 전력을 획기적으로 절감(Weight/Output Stationary Dataflow), XLA(Accelerated Linear Algebra) 컴파일러를 통한 정적 그래프 융합 및 메모리 사전 할당 극대화, 광 회로 스위치(OCS) 기반의 초고속 ICI 패브릭을 통한 수만 개 칩 무손실 팟(Pod) 스케일아웃**을 달성할 필요

#### 한줄 요약

- 인접 MAC 간 데이터 재사용 기반 **시스톨릭 배열**

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시스톨릭 배열(Systolic Array)**: 데이터가 인접 MAC 사이를 박동처럼 흐르며 재사용되는 연산 배열이다.
- **곱셈 누산(Multiply-Accumulate, MAC)**: 곱셈 결과를 누적해 행렬 연산을 구성하는 계산이다.
- **고대역폭 메모리(High Bandwidth Memory, HBM)**: 적층 구조로 넓은 메모리 대역폭을 제공하는 메모리이다.
- **칩 간 상호연결(Inter-Chip Interconnect, ICI)**: TPU 칩 사이의 데이터를 교환하는 연결망이다.

</details>

- 시스톨릭 MXU의 **MAC 간 데이터 재사용**
- HBM•ICI 기반 **텐서 공급•다칩 병렬**
- 그래프 컴파일 기반 **연산 융합•타일•칩 배치**

#### 한줄 요약

- 고정 형상은 MXU 점유율 증가, **가변 형상** 유휴 증가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **전용 컴파일러**: 모델 그래프를 텐서 처리장치가 지원하는 연산•배치•메모리•칩 분할 계획으로 변환하는 개념이다.

</details>

```text
[TPU Architecture]
├── [호스트 및 컴파일러 계층]
│   ├── [호스트·입출력 (Host & I/O)]
│   └── [전용 컴파일러 (XLA Compiler)]
├── [메모리 및 인터커넥트 계층]
│   ├── [HBM (High Bandwidth Memory)]
│   └── [칩 간 상호연결 (ICI Interconnect)]
└── [연산 코어 계층]
    └── [텐서 코어 (MXU & Vector Unit)]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 호스트•입출력 | **모델 제어•입력•결과** 관리 |
| 전용 컴파일러 | 모델을 변환하는 **TPU 실행 코드** |
| HBM | **가중치•활성값 저장•공급** |
| 텐서 코어 | **MXU•벡터•스칼라 연산** 분담 |
| 칩 간 상호연결 | **ICI 집합 통신•파티션** 교환 |

#### 한줄 요약

- 컴파일러•HBM•텐서 코어•ICI의 **TPU 구조**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타일**: 큰 텐서를 MXU와 HBM 용량에 맞춰 나눈 계산 블록이다.
- **파티션**: 모델•데이터 연산을 여러 TPU 칩에 배치하기 위해 나눈 작업 단위이다.

</details>

HBM 타일 공급과 다중 TPU **파티션 배치** 흐름

```text
호스트•입출력 ── 모델 그래프•형상 ──▶ 전용 컴파일러
전용 컴파일러 ── 1. 타일•파티션 계획 ──▶ HBM
HBM ── 2. 텐서 타일 ──▶ 텐서 코어
┌──────── 다칩 연산 완료까지 ────────┐
│ 텐서 코어 ── 3. MXU 행렬•벡터 연산
│ 텐서 코어 ── 4. 집합 통신 데이터 ──▶ 칩 간 상호연결
│ 텐서 코어 ◀── 집합 통신 결과 ───── 칩 간 상호연결
└────────────────────────────────────┘
HBM ◀─ 5. 다칩 연산 결과 저장 ── 텐서 코어
호스트•입출력 ◀── 최종 결과 ───── HBM
```

### 동작 원리

1. 타일•파티션 계획: 연산 융합•MXU•칩 배치 결정
2. 텐서 타일: HBM의 가중치•활성값 공급
3. MXU 행렬•벡터 연산: 시스톨릭 배열에서 곱셈•누산
4. 집합 통신 데이터: 칩 간 파티션 결과 교환
5. 다칩 연산 결과 저장: 결합 결과를 HBM에 기록

#### 한줄 요약

- 타일 배치 후 **MXU 연산•ICI 집합 통신** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **그래프 컴파일**: 모델 연산을 융합하고 텐서와 칩 배치를 정해 TPU 실행 코드로 변환하는 과정이다.
- **단일 명령 다중 스레드(Single Instruction, Multiple Threads, SIMT)**: 여러 스레드가 같은 명령을 실행해 다양한 데이터 병렬 연산을 처리하는 그래픽 처리장치 방식이다.
- **중앙처리장치(Central Processing Unit, CPU)**: 복잡한 제어와 순차 작업을 처리하는 범용 프로세서이다.
- **그래픽 처리장치(Graphics Processing Unit, GPU)**: 대량 데이터에 같은 연산을 병렬 적용하는 프로세서이다.

</details>

TPU•CPU•GPU의 **행렬 전용성•제어 유연성** 비교

| 프로세서 | TPU | CPU | GPU |
|:---|:---|:---|:---|
| 적용 기준 | **반복 행렬 연산•고정 형상** | **제어•비정형 연산** | **다양한 병렬 연산•모델 변경** |
| 핵심 특징 | **시스톨릭 MXU•그래프 컴파일** | **범용 코어•독립 제어** | **SIMT•텐서 코어** |
| 한계 | **지원 연산•형상 제약** | **행렬 처리량 제한** | **분기•전송 오버헤드** |

> 요약: **CPU**는 제어, **GPU**는 범용 병렬, TPU는 행렬 전용

#### 한줄 요약

- 제어는 CPU, 범용 병렬은 GPU, **행렬 전용은 TPU**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **형상 버킷**: 크기가 비슷한 입력을 묶어 정해진 텐서 형상으로 실행하는 최적화 방법이다.
- **집합 통신**: 여러 칩이 계산 결과를 합산•분배•교환해 공동 상태를 만드는 통신 연산이다.

</details>

**MXU 이용률**과 ICI 통신량의 공동 최적화

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 작은•가변 형상으로 **MXU 이용률** 저하 | 형상 버킷•행렬 타일 패딩 적용 | 시스톨릭 배열 **점유율 향상** |
| 다칩 파티션의 **ICI 통신 병목** | 텐서•데이터 병렬 배치 최적화 | 집합 통신 **대기 감소** |

#### 한줄 요약

- 형상 버킷과 칩 배치로 **MXU 이용률•ICI 통신** 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **고정 형상**: 실행 전에 텐서의 차원과 크기가 일정하게 정해진 연산 형태이다.
- **가변 연산**: 입력이나 모델에 따라 계산 구조와 텐서 형상이 자주 달라지는 연산이다.

</details>

- 구글의 글로벌 AI 서비스(검색, 유튜브, 제미나이)와 대규모 클라우드 AI 학습을 전담하는 **초대형 AI 훈련 및 행렬 연산 특화 도메인 전용 프로세서(DSA)의 최고 표준(Google TPU / 2D Systolic Matrix Multiply Unit / TPU v5p & v6 Trillium Pod / XLA Compiler & Static Graph Fusion / Optical Circuit Switch: OCS Interconnect / Bfloat16 Numerical Standard)의 확고한 표준**으로 확고히 자리 잡았으며, 초대형 TPU 팟(Pod)을 통한 엑사스케일 AI 분산 학습을 주도하는 가운데, 실무 인프라 선정 시에는 **정적 그래프와 고정 텐서 형상(Static Shape) 기반의 초대형 LLM/트랜스포머 학습에는 TPU 팟을 우선 채택하고, 동적 그래프와 비정형 모델 연구에는 GPU 생태계를 선택하며, 텐서 차원을 MXU 크기(128x128) 배수로 정렬(Padding)하여 하드웨어 가동률을 극대화**를 결합하여 완벽한 TCO 절감과 대규모 분산 학습 성능을 완성

#### 한줄 요약

- 고정 형상•반복 행렬은 TPU, **가변 연산**은 GPU 선택
