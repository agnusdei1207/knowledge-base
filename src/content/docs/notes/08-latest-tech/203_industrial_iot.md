## 미리 알고가기

- **IIoT(산업용 사물인터넷)**: 설비·센서를 네트워크로 연결해 데이터 분석·제어를 수행하는 구조
- **요구 수준**: 실시간성, 신뢰성, 안전성이 소비자 IoT보다 높음
- **운영 핵심**: Edge Computing, OT 보안, 장기 장비 수명 관리가 중요함



## Ⅰ. 개요

- **정의/개념**: 산업 설비를 엣지·플랫폼·분석과 연결
- **배경/필요성**: 분산 설비의 정지·품질·안전 비용을 절감

### 쉽게 이해하기 (학습용)

- 산업 현장의 감각기관과 제어기를 연결해 분석하고 안전하게 운영함

## Ⅱ. 특징

- 현장·엣지가 실시간 제어와 전처리를 유지한다.
- 연결·플랫폼이 장치·시계열 데이터를 통합한다.
- 분석 결과가 승인·인터록을 거쳐 현장에 반영된다.
- 신뢰성 경계가 안전·보안·복원력을 함께 다룬다.

### 쉽게 이해하기 (학습용)

- 현장 제어는 안전을 우선하고, 분석은 승인 후 적용함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| Asset | 산업 장비 및 자산 식별 |
| Edge | 데이터 수집 및 현장 실시간 제어 |
| Connectivity | 산업 통신 프로토콜 및 망 구성 |
| Data Platform | 데이터 수집 및 자산 모델링 |
| Analytics | 디지털 트윈 기반 지능 분석 |
| Trust/Security | OT 보안 및 안전 조치 실행 |

> 요약: 현장 제어 유지 및 안전 승인 기반 지능 분석 체계임

### 쉽게 이해하기 (학습용)

- 현장 반사신경은 기계 가까이에 두고 관제소로 안전하게 기록을 보내 분석하며, 중앙 지시는 현장 안전문을 통과한 것만 적용하는 구조임

## Ⅳ. 원리 및 절차 흐름도

자산등록
 ↓
센싱검증
 ↓
데이터전송
 ↓
데이터분석
 ↓
조치환류

| 절차 | 설명 |
|:---|:---|
| asset·위험 등록 | asset·위험 등록을 수행하고 결과를 검증함 |
| sensing·edge 검증 | sensing·edge 검증을 수행하고 결과를 검증함 |
| 안전한 전송·buffer | 안전한 전송·buffer을 수행하고 결과를 검증함 |
| platform·analytics | platform·analytics을 수행하고 결과를 검증함 |
| 승인·local actuation·feedback | 승인·local actuation·f을 수행하고 결과를 검증함 |

> 요약: Edge 기반 데이터 검증과 안전 승인 환류 절차임

### 쉽게 이해하기 (학습용)

- 기계 신분과 위험을 정하고 현장에서 측정값을 검사해 통신이 끊기면 보관하며, 중앙 분석 결과는 안전 승인 후 적용하고 효과를 다시 측정함

## Ⅴ. 종류 및 비교

| 판단 기준 | IIoT | Consumer IoT | 전통 SCADA |
|:---|:---|:---|:---|
| 핵심 특징 | 산업 자산·분석·현장 환류 연결 | 소비자 편의·개인화 중심 | 중앙 감시·폐쇄망 제어 중심 |
| 적용 기준 | 예지정비·품질·생산 최적화 | 가정·wearable 원격 서비스 | 안정된 설비의 결정적 감시 |
| 주요 위험 | legacy 공격이 안전에 영향 | 개인정보·짧은 제품 수명 | 외부 통합·확장성 제약 |

> 요약: 장기 운영을 위해 분석 결과를 안전하게 환류함

### 쉽게 이해하기 (학습용)

- 가정용 편의 장치, 공정 감시실, 여러 산업 현장을 연결한 안전한 분석망은 장애 영향과 수명·통신·보안 방식이 다름

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 원격 풍력단지는 edge가 진동·온도 data를 분석하고 불안정한 회선 동안 store-and-forward하며, 중앙 예측 결과를 정비 order로 보내고 turbine 보호 제어는 local에 유지함
- 화학 공장은 pump·valve sensor를 OT zone에 두고 gateway를 거쳐 historian·analytics로 보내 cavitation을 예측하되 remote access는 OT DMZ jump host와 시간 제한 승인으로 통제함

## Ⅶ. 결론

- 현장 자율성·안전 경계로 IIoT 피드백 범위 결정

### 쉽게 이해하기 (학습용)

- 기계를 많이 인터넷에 붙이는 것보다 통신이 끊기거나 공격받아도 안전하게 운영되고 분석이 실제 정비·품질 개선으로 이어지는지가 중요함
