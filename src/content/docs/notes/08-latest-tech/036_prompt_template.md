## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **프롬프트 템플릿(Prompt Template)**: 고정 지시와 검증된 변수값, 출력 계약을 결합해 반복 호출에 재사용하는 프롬프트 서식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **재현성**: 같은 템플릿•모델•입력 조합에서 일관된 처리 조건과 결과 형식을 다시 구성할 수 있는 성질로 정의된다.

</details>

- 정의/개념: 고정 지시•검증된 입력 슬롯•출력 계약을 결합해 같은 작업에 반복 사용하는 **프롬프트 템플릿**임. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출함.
- 배경/필요성: 요청마다 직접 작성하면 지시•입력 검증•결과 형식이 달라져 **재현성**이 깨진음.

#### 한줄 요약
- 고정 지시와 **검증된 변수•출력 계약**을 결합한 서식 구조 구현

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **정적 블록(Static Block)**: 실행마다 바뀌지 않는 역할•목표•제약 문구다.
- **변수 슬롯(Variable Slot)**: 실행 시 업무값이 들어가도록 이름•자료형•제약이 정의된 자리다.
- **회귀 검증(Regression Test)**: 템플릿•모델•출력 계약 변경 뒤 기존 과업의 품질 저하 여부를 확인하는 시험로 정의된다.

</details>

- **정적 블록**: 반복 업무의 공통 지시를 재사용하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **변수 슬롯**: 실행별 업무값이 들어갈 입력 자리를 정의하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **슬롯 검증**: 자료형•길이•허용값을 판정하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **안전 결합**: 검증값을 이스케이프 후 삽입하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **통합 버전 관리**: 템플릿•모델•출력 계약의 호환 조합을 고정하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.
- **회귀 검증**: 변경 후 기존 과업의 품질 저하 여부를 확인하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **슬롯•출력•모델 버전**의 호환 조합을 함께 검증 체계 적용

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **렌더러(Renderer)**: 검증한 변수값을 지정 슬롯에 결합하여 완성 프롬프트를 만드는 구성요소다.
- **정적 지시 블록**: 반복 작업에 공통으로 적용할 역할•목표•절차•제약을 고정한 부분을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **변수 명세**: 각 입력 슬롯의 이름•자료형•필수 여부•허용 범위와 이스케이프 규칙을 정한 계약로 정의된다.
- **이스케이프(Escaping)**: 따옴표•줄바꿈 같은 제어 문자가 템플릿 구조를 바꾸지 않도록 안전한 표현으로 변환하는 처리다.
- **버전 저장소**: 템플릿•호환 모델•평가 결과의 변경 이력을 보존해 실행을 재현하는 저장소을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

```text
[정적 지시 블록]       [변수 명세]
          \                /
             [검증•렌더러] ----- [출력 계약]
                    |
              [버전 저장소]
```

선의 의미: 검증•렌더러는 정적 지시 블록과 변수 명세의 경계를 결합하고 출력 계약에 맞는 프롬프트 구성을 제공하며, 버전 저장소는 이 호환 조합의 정적 재현 기반을 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 정적 지시 블록 | 역할•목표•제약의 **공통 문구** 유지 |
| 변수 명세 | 자료형•필수 여부•**길이•권한** 정의 |
| 검증•렌더러 | 입력 검사 후 **이스케이프** 결합 |
| 출력 계약 | 필드•자료형•**오류•근거 규칙** 명시 |
| 버전 저장소 | 호환 조합과 **승인 이력** 관리 |

#### 한줄 요약
- **지시•변수•렌더러•출력•버전**을 구성 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **슬롯 검증**: 변수값의 자료형•길이•허용값•접근 권한을 렌더링 전에 판정하는 절차다.
- **호환 조합**: 함께 검증된 템플릿•모델•출력 계약의 버전 묶음로 정의된다.

</details>

```text
템플릿 실행 요청
       │
       ▼
렌더러
       │ 1. 승인 템플릿 버전 로드
       │ 슬롯 입력 전달
       ▼
검증기
       │ 2. 슬롯 입력 검증
       │ 안전한 값 반환
       ▼
렌더러
       │ 3. 고정 지시•검증값 렌더링
       │ 완성 프롬프트 전달
       ▼
모델
       │ 모델 출력 반환
       ▼
검증기
       │ 4. 출력 계약 검증
       │ 검증 결과 반환
       ▼
관리자
```

1. **승인 템플릿 버전 로드**: 지시•변수•출력 계약의 호환 조합을 호출함.
2. **슬롯 입력 검증**: 자료형•길이•허용값•접근 권한을 판정함.
3. **고정 지시•검증값 렌더링**: 이스케이프 후 지정 슬롯을 결합함.
4. **출력 계약 검증**: 응답 구조와 업무 규칙 충족 여부를 판정함.

#### 한줄 요약
- **버전 로드•슬롯 검증•렌더링•출력 검증**을 수행 체계 적용

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **임시 프롬프트**: 일회성 탐색을 위해 요청마다 지시를 직접 구성하는 방식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
</details>

| 프롬프트 작성 방식 | 임시 프롬프트 | 프롬프트 템플릿 |
|:---|:---|:---|
| 적용 기준 | **일회성 탐색•실험** | 반복 업무•**공통 출력 형식** |
| 핵심 특징 | 요청마다 **지시 직접 구성** | **고정 블록•검증 슬롯** 재사용 |
| 한계 | 작성자별 편차•**재현성 부족** | 슬롯 경계•**버전 호환성 관리** |

#### 한줄 요약
- 일회성은 **임시 프롬프트**, 반복 업무는 **템플릿**이 적합하 기전 적용

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **구분자(Delimiter)**: 지시와 외부 데이터를 서로 다른 영역으로 표시하여 경계를 명확히 하는 기호다.
- **프롬프트 주입(Prompt Injection)**: 외부 입력의 지시가 고정 지시를 무시하거나 우회하도록 모델을 유도하는 공격이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **슬롯 입력 오염**: 검증되지 않은 변수값이 제어 문자나 지시를 포함하여 템플릿의 의도와 구조를 바꾸는 문제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **슬롯 입력 오염** | 자료형•허용값 검증과 **이스케이프** | 형식 오류•**제어 문자 주입 억제** |
| **지시•데이터 경계 혼동** | **구분자•비신뢰 데이터 표식** 적용 | **프롬프트 주입** 방지 |
| **버전 조합 불일치** | 템플릿•모델•**출력 계약 버전** 고정 | **배포 재현성 확보** |
| **출력 의미 오류** | 출력 계약 후 **업무 규칙 검증** | 의미 오류의 **탐지 강화** |

#### 한줄 요약
- **슬롯•경계•버전•업무 규칙**을 함께 검증 체계 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **업무 반복성**: 같은 지시•입력•출력 형식이 반복되는 작업의 성격을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **업무 정형성**: 결과 형식과 절차가 사전에 정의되어 동일하게 적용 가능한 작업의 성격이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 일회성 탐색은 **임시 프롬프트**, 반복•정형 업무는 **템플릿**을 선택하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함.

#### 한줄 요약
- **업무 반복성•정형성**에 따라 임시•템플릿을 선택 체계 적용
