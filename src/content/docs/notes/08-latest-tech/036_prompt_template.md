## 미리 알고가기

- **프롬프트 템플릿(Prompt Template)**: 고정 지시와 변수 슬롯을 둔 재사용 서식
- **변수 슬롯(Variable Slot)**: 실행 시 값을 채우는 입력 자리
- **슬롯 바인딩(Slot Binding)**: 검증된 값을 지정 슬롯에 결합
- **스키마(Schema)**: 입력·출력 필드와 자료형 정의
- **이스케이프(Escaping)**: 제어 문자를 안전한 표현으로 변환
- **구분자(Delimiter)**: 지시와 비신뢰 데이터 경계 표시



## Ⅰ. 개요

- 정의/개념: 고정 지시·변수 슬롯의 재사용 서식
- **배경/필요성**: 자유 입력 프롬프트만으로 반복 업무의 지시·변수·출력 형식 일관성 확보 곤란

### 쉽게 이해하기 (학습용)

- 공통 문장은 고정하고 항목별 값만 안전하게 채우는 업무용 서식

## Ⅱ. 특징

- **지시·데이터·출력 계약** 경계 명시
- 슬롯별 타입·길이·허용값과 **입력 검증**
- 템플릿·모델·스키마의 **통합 버전 관리**

### 쉽게 이해하기 (학습용)

- 입력 형식과 길이를 검사해 서식 오류와 지시 오염을 예방

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 정적 블록 | 역할·목표·제약 고정 |
| 변수 명세 | 자료형·필수·길이·민감도 정의 |
| 렌더러 | 값 검증 후 슬롯 결합 |
| 출력 계약 | 스키마·오류·근거 규칙 정의 |
| 저장·평가 | 버전·승인·회귀 관리 |

```text
프롬프트 템플릿
├─ 정적 블록
├─ 변수 명세
├─ 렌더러
├─ 출력 계약
└─ 저장·평가
```

### 쉽게 이해하기 (학습용)

- 서식 버전과 검증된 값, 결과 형식을 묶어 실행 전에 완성된 문서를 확인함

## Ⅳ. 원리 및 절차 흐름도

```text
계약정의
  ↓
등록검토
  ↓
입력검증
  ↓
안전결합
  ↓
결과검증
```

| 절차 | 설명 |
|:---|:---|
| 계약정의 | 고정 지시·변수·출력 규칙 수립 |
| 등록검토 | 보안·업무 검토 후 버전을 등록 |
| 입력검증 | 슬롯 자료형·길이·권한 검사 |
| 안전결합 | 이스케이프 후 슬롯에 값 결합 |
| 결과검증 | 출력 스키마·업무 규칙 준수 검사 |

### 쉽게 이해하기 (학습용)

- 공용 서식도 배포 전 검증하고 실제 사용 중 실패한 값과 사례를 다음 버전에 반영해야 함

## Ⅴ. 프롬프트 작성 방식 비교

| 구분 | 임시 프롬프트 | 프롬프트 템플릿 |
|:---|:---|:---|
| 작성 방식 | 요청마다 직접 작성 | 고정 블록·슬롯 재사용 |
| 변경 관리 | 작성자별 문구 차이 | 버전·승인으로 배포 |
| 적용 기준 | 일회성 탐색 과업 | 반복 업무·공통 형식 |
| 핵심 특징 | 요청마다 자유 작성 | 고정 지시·검증 슬롯 재사용 |
| 한계 | 품질 편차·재현성 부족 | 슬롯 경계·인젝션 통제 필요 |

> 요약: 공용 서식은 표준화와 관리에 적합함

### 쉽게 이해하기 (학습용)

- 매번 새로 쓰는 요청서보다 공용 서식은 일관되지만 빈칸 검증과 버전 관리가 필요함

## Ⅵ. 실무 사례

- 고객 데이터·내부 규정을 나누고 민감값을 검사한다
- 변수 입력에 최소 권한·도구 인자 검증을 적용한다

### 쉽게 이해하기 (학습용)

- 따옴표로 구역을 나눠도 안의 악성 문장이 모델 행동에 영향을 줄 수 있어 권한 통제가 필요함

## Ⅶ. 결론

- 고정 지시·타입 슬롯·출력 계약을 버전 관리한다
- 검증·이스케이프·권한으로 슬롯 주입을 막는다

### 쉽게 이해하기 (학습용)

- 좋은 서식은 반복 업무를 빠르게 하며 빈칸 검증은 안전한 운영의 핵심
