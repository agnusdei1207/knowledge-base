## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **에이전틱 인공지능(Agentic Artificial Intelligence, Agentic AI)**: 주어진 목표를 하위 작업으로 분해하고, 도구 실행(Tool Execution)·관찰(Observation)·재계획(Replanning) 루프를 자율적으로 반복하여 목표를 완수하는 시스템 아키텍처임. 이는 사람의 개입 없이도 복합 업무를 종단 간(End-to-End) 수행하도록 설계된 자율형 실행 패러다임을 통칭함.

</details>

- 정의/개념: 목표를 작업 단위로 분해하고 도구 실행·관찰·재계획을 반복적으로 수행하여 완료 조건을 충족할 때까지 능동적으로 움직이는 **Agentic AI**임. 이는 단일 응답에 그치는 생성형 AI와 구별되며, 실질적인 업무 자동화 가치를 창출하는 핵심 차별점임.
- 배경/필요성: 생성형 AI가 단발성 응답(Single-Turn Response)에 머무르는 한계로 인해 장기 상태 관리, 예외 복구, 다단계 의사결정 과정에서 운영 리스크가 누적됨에 따라, 이를 체계적으로 해결할 실행형 아키텍처의 필요성이 대두됨.

#### 한줄 요약
- **Agentic AI**가 목표를 작업으로 나누고 완료까지 수행하는 자율 실행 체계 적용.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **목표 지향성(Goal-Oriented)**: 추상적인 목표를 의존 관계가 있는 하위 작업과 측정 가능한 완료 조건(Completion Condition)으로 변환하는 설계 특성이며, 이는 정해진 결과물에 수렴하도록 에이전트를 유도하여 실행의 구조적 완결성을 보장하는 핵심 기제임.
- **자기 성찰(Self-Reflection)**: 도구 실행 후 반환된 관찰 결과와 오류 신호를 평가하여 다음 행동 경로(Plan-of-Action)를 동적으로 수정하는 특성을 말하며, 실무적 관점에서 시스템의 안정적 수렴과 비용 효율성을 보장하는 자기 교정 메커니즘임.
- **비동기 자율성(Asynchronous Autonomy)**: 장기·다단계 작업의 중간 상태와 복구 지점(Checkpoint)을 저장 매체에 영속화하고, 사람의 판단이나 외부 이벤트 발생 시 실행을 안전하게 재개하는 능력을 의미하며, 이는 시스템의 구조적 완결성을 높이고 외부 환경 변화에 대한 회복탄력성을 제공하는 핵심 설계 요소임.

</details>

- **목표 지향성(Goal-Oriented)**: 목표를 의존성 그래프(Dependency Graph) 기반의 실행 작업과 검증 가능한 완료 조건으로 변환하여, 환경 변화에 따른 실무적 유연한 대응과 지속적 최적화를 지원함.
- **자기 성찰(Self-Reflection)**: 관찰 결과와 오류 패턴에 따라 행동 경로를 능동적으로 수정하여, 실패에 대한 실무적 유연한 대응과 작업 흐름의 지속적 최적화를 지원함.
- **비동기 자율성(Asynchronous Autonomy)**: 상태(State)·권한(Authority)·승인(Approval) 규칙으로 중단 및 복구 조건을 강제하여, 예외 발생 시 실무적 유연한 대응과 작업 신뢰성의 지속적 최적화를 지원함.

#### 한줄 요약
- **자기 성찰(Self-Reflection)**로 대체 경로를 찾아 목표 수행을 지속하는 자기 교정 체계 적용.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **작업 메모리(Working Memory)**: 현재 목표(Goal)·계획(Plan)·관찰 결과(Observation)·도구 실행 결과를 단기 보존하여 후속 LLM 추론과 행동 결정에 직접 활용되는 인메모리(In-Memory) 상태 저장소이며, 이는 컨텍스트 연속성을 유지하여 에이전트의 구조적 완결성과 차별화된 추론 성능을 보장하는 핵심 기술 기반임.
- **대규모 언어 모델(Large Language Model, LLM)**: 자연어로 표현된 목표와 작업 문맥(Context)을 입력받아 다음 단계의 계획과 행동 후보(Tool Call)를 생성하는 추론 엔진이며, 이는 에이전트의 두뇌 역할을 수행하여 구조적 완결성을 높이는 핵심 기술 기반임.
- **계획 모듈(Planning Module)**: 상위 목표를 DAG(Directed Acyclic Graph) 형태의 의존 관계가 있는 실행 가능한 하위 작업으로 분해하고 순서를 결정하는 구성요소를 지칭하며, 실행 전략의 청사진을 제공하는 핵심 모듈임.
- **평가 모듈(Evaluation Module)**: 도구 실행 후 반환된 관찰 결과와 사전 정의된 완료 조건을 대조하여 재계획(Replan), 재시도(Retry), 종료를 결정하는 구성요소이며, 이는 에이전틱 루프의 자기 교정 단계를 담당하여 구조적 완결성과 결과 신뢰성을 보장함.
- **권한 정책(Authorization Policy)**: 에이전트가 호출 가능한 도구(Tool)·데이터(Data)·행동 범위와 사람의 명시적 승인(HITL)이 필요한 지점을 정의하는 통제 규칙 집합을 의미하며, 시스템의 자율적 판단과 외부 실행 사이의 안전 경계를 설정하는 핵심 아키텍처 요소임.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 에이전트가 외부 시스템의 기능을 인증(Authentication)·인자(Argument) 검증·권한 스코프(Scope) 규칙에 따라 호출하도록 중개하는 인터페이스 규격이며, 이는 외부 자원을 구조적으로 통합하여 차별화된 성능을 제공하는 기술 기반임.
- **데이터베이스(Database, DB)**: 작업의 진행 상태, 사용된 토큰/비용, 복구 지점, 그리고 감사 로그(Audit Log)를 영속적으로 저장하는 저장소이며, 이는 시스템의 구조적 완결성을 높이고 장기 작업의 신뢰성 있는 재개 및 추적성을 제공하는 기술 기반임.

</details>

```text
                 [목표•정책]
                      |
                 [계획•평가]
                      |
          +-----------+-----------+
          |                       |
     [도구•권한]              [상태•감사]
```

선의 의미: 최상위 목표·정책 계층 아래 계획·평가 모듈이 도구·권한 경계(Trust Boundary)와 상태·감사 저장소를 동시에 참조·통제하는 에이전틱 AI의 표준 아키텍처 구조를 나타냄.

| 구성요소 | 책임 |
|:---|:---|
| 목표•정책 | **LLM**과 **권한 정책(Authorization Policy)** 을 결합하여 목표, 완료 조건, 위험도, 자율 수준(Autonomy Level)을 정의함 |
| 계획•평가 | **계획 모듈(Planning Module)** 과 **평가 모듈(Evaluation Module)** 이 행동 후보와 관찰 결과를 평가하여 다음 상태 전이를 결정함 |
| 도구•권한 | **API** 인증, 함수 인자(Argument) 검증, 실행 권한 부여를 중개하여 외부 호출을 통제함 |
| 상태•감사 | **작업 메모리(Working Memory)** 와 **DB** 에 진행 상태, 토큰/비용, 복구지점(Checkpoint)을 기록함 |

#### 한줄 요약
- **권한 정책(Authorization Policy)** 이 계획·도구·상태·승인을 통합해 자율 실행을 통제하는 거버넌스 체계 적용.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **인간 참여형 통제(Human-in-the-Loop, HITL)**: 고위험 행동을 실행하기 전에 사람이 맥락(Context)과 잠재적 영향을 검토하고 명시적으로 승인·거부하는 통제 방식을 의미하며, 이는 에이전트에게 광범위한 자율 권한을 위임하는 환경에서 구조적 완결성과 결과 신뢰성을 보장하는 핵심 기술 기반임.
- **목표·완료 조건·과업계획 전달(Goal Provision)**: 사람이 에이전트에게 작업 목록, 의존성(Dependency), 예외 경로(Exception Path), 자율 수준(Autonomy Level)을 설정하여 위임하는 단계를 의미하며, 이는 실행 범위와 제약 조건을 명확히 함으로써 구조적 완결성을 높이는 핵심 시작 단계임.
- **위험·권한·승인 조건 제공(Risk Assessment)**: 행동이 환경에 미치는 영향(Impact), 허용 가능한 권한 스코프, 그리고 사람의 HITL 승인이 개입해야 하는 지점을 판정하는 단계를 말하며, 실무적 관점에서 안정적인 자율 실행과 운영 효율성을 보장하는 주요 거버넌스 기전임.
- **허가된 행동·인자 실행 요청(Action Request)**: 정책 검증을 통과한 도구(Tool)와 인자(Argument)로 외부 시스템의 실행을 요청하는 단계를 의미하며, 이는 통제된 외부 자원 접근을 통해 구조적 완결성을 높이는 핵심 기술 기반임.
- **실행 결과·오류 반환(Execution Return)**: 외부 환경에서 반환된 관찰값(Standard Output)과 실패 원인(Error Trace/Exception)을 에이전트에게 제공하는 단계이며, 이는 다음 추론을 위한 입력 데이터를 생성하여 구조적 완결성을 높이는 핵심 기술 기반임.
- **관찰 결과·재계획 또는 종료안 제출(Observation Submission)**: 관찰값과 완료 조건을 대조하여 작업의 완료, 재개, 중단, 또는 사람의 인적 이관(Handoff) 중 다음 상태를 최종 결정하는 단계를 의미하며, 이는 에이전틱 루프의 핵심 마무리를 담당하여 구조적 완결성을 높이는 기술 기반임.

</details>

```text
에이전트
   │ 1. 목표•완료 조건•과업계획 전달
   ├───────────────────┐
   │ 완료•중단 전까지 │
   └─────────┬─────────┘
   ▼
성찰기
   │ 2. 위험•권한•승인 조건 제공
   ▼
에이전트
   │ 3. 허가된 행동•인자 실행 요청
   ▼
도구
   │ 4. 실행 결과•오류 반환
   ▼
에이전트
   │ 관찰 결과 전달
   ▼
성찰기
   │ 5. 관찰 결과•재계획 또는 종료안 제출
   ▼
에이전트
```

### 동작 원리

1. **목표·완료 조건·과업계획 전달(Goal Provision)**: 사람이 **완료 조건(Completion Condition)** 과 작업 목록, 의존성, 예외 경로, 자율 수준을 설정하여 에이전트에게 위임함.
2. **위험·권한·승인 조건 제공(Risk Assessment)**: 행동이 미치는 영향과 허용 권한 스코프를 평가하고, 고위험 시 **HITL** 개입 지점을 판정함.
3. **허가된 행동·인자 실행 요청(Action Request)**: 정책 검증을 통과한 도구 호출(Tool Invocation)과 그에 따른 진행 상태를 작업 메모리에 기록함.
4. **실행 결과·오류 반환(Execution Return)**: 외부 환경에서 반환된 관찰값과 실패 원인을 표준화된 스키마로 제공함.
5. **관찰 결과·재계획 또는 종료안 제출(Observation Submission)**: 완료 조건 충족 여부에 따라 작업 완료, 재개, 중단, 인적 이관(Handoff) 중 다음 상태를 결정함.

#### 한줄 요약
- **관찰 결과·재계획 또는 종료안 제출(Observation Submission)** 로 다음 상태를 결정하는 제어 루프 체계 적용.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **생성형 인공지능(Generative Artificial Intelligence, Generative AI)**: 입력 프롬프트에 따라 텍스트·이미지·코드 등 새로운 콘텐츠를 단발적으로 합성하는 인공지능을 의미하며, 시스템의 자율적 판단과 다단계 실행 없이 콘텐츠 생성에 집중하는 핵심 아키텍처 요소임.
- **에이전틱 워크플로(Agentic Workflow)**: 목표 달성을 위해 계획(Plan) → 행동(Act) → 관찰(Observe) → 성찰(Reflect)의 4단계를 순환하며 작업을 점진적으로 완성하는 실행 방식이며, 이는 동적 환경에서 문제를 해결함에 있어 구조적 완결성을 높이고 차별화된 성능을 제공하는 핵심 기술 기반임.

</details>

| 판단 기준 | 에이전틱 AI | 생성형 AI |
|:---|:---|:---|
| 적용 기준 | **Agentic AI** 는 장기·다단계 목표를 계획·실행·완료까지 종단 간(End-to-End)으로 수행함 | **Generative AI** 는 사용자 입력을 받아 단발성 콘텐츠를 즉시 생성함 |
| 핵심 특징 | **에이전틱 워크플로(Agentic Workflow)** 의 목표-계획-행동-관찰 루프를 통해 자율적으로 진화함 | 사전 학습된 모델 파라미터에 기반하여 입력에 대한 콘텐츠를 단순히 생성함 |
| 한계 | 토큰 비용 증가, 도구 호출 오류 누적, 권한 오용(Misuse) 위험이 존재함 | 장기 목표 상태 유지, 외부 도구 실행, 동적 예외 복구 능력이 본질적으로 부족함 |

> 요약: **Agentic AI**는 외부 도구를 결합하여 목표를 실행하는 '행동 중심' 패러다임이며, **Generative AI**는 입력으로부터 콘텐츠를 합성하는 '생성 중심' 패러다임임.

#### 한줄 요약
- 단발 생성은 **Generative AI**, 목표 반복은 **Agentic AI** 가 핵심인 패러다임 구분 체계 적용.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **완료 조건(Completion Condition)**: 에이전트가 목표 달성 여부를 객관적으로 검증하고 작업 루프를 종료할 수 있도록 정한 측정 가능한 기준(예: 정량 지표, 함수 반환값, Boolean Flag)을 의미하며, 실무적 관점에서 무한 루프 방지, 비용 한도 통제, 결과 신뢰성을 보장하는 주요 운영 기전임.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 완료 조건 모호로 인한 무한 실행 및 비용 폭증 | **완료 조건(Completion Condition)** 과 최대 반복 횟수·비용 한도(Cost Limit)를 강제 설정함 | 명확한 종료 시점을 확보하여 자원 고갈 및 무한 루프 위험을 방지함 |
| 오류가 후속 행동에 번지는 상태 오염(State Contamination) | **작업 메모리(Working Memory)** 의 신뢰도 향상과 복구지점(Checkpoint) 기반의 재계획(Replan)을 적용함 | 잘못된 상태가 후속 단계로 전파되는 것을 억제하여 실행 무결성을 확보함 |
| 고영향·책임 소재(Service-Disrupting) 작업의 통제 부재 위험 | **HITL** 명시적 승인 단계와 감사 로그(Audit Log) 기록 체계를 의무화함 | 자율성과 책임성(Accountability)의 균형을 유지하여 운영 리스크를 경감함 |

#### 한줄 요약
- 위험도별 **권한 정책(Authorization Policy)** 과 **HITL** 승인을 적용한 단계별 통제 체계 적용.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **자율성 통제(Autonomy Control)**: 권한 스코프, 실행 비용, 시간 한도, 승인 경계(Approval Boundary)를 종합적으로 적용하여 에이전트가 독립적으로 행동할 수 있는 범위(Autonomy Level)를 제한하는 운영 원칙을 의미하며, 이는 시스템의 구조적 완결성을 높이고 자율 실행으로 인한 리스크를 통제하는 핵심 기술 기반임.

</details>

- 장기·다단계 목표에는 **Agentic AI** 아키텍처를 도입하고, 고영향·책임 소재가 큰 행동에는 반드시 **HITL** 승인을 결합 적용하여 실무 환경에서의 유연한 대응과 지속적 최적화를 지원함. 이는 자율성의 확장성과 운영 거버넌스 간의 균형을 맞추기 위한 필수 요건임.

#### 한줄 요약
- **자율성 통제(Autonomy Control)** 원칙 하에 승인 지점·중단·복구 절차를 명문화 반영한 거버넌스 체계 적 적용.
