## 미리 알고가기

- **데이터 패브릭 (Data Fabric) 분산 자산 통합 아키텍처**: 메타데이터와 자동화로 자산을 연결함
- **저장소 개념**: 물리적 저장소 통합이 아닌 상위의 통합 계층을 구성함
- **핵심 요소**: 활성 메타데이터, 지식 그래프, 정책 자동화를 주로 활용함

## 작성 근거(검토용)

- **방향성**: 이기종 데이터 위치를 유지하면서 기술·업무·운영 metadata와 knowledge graph를 통합해 접근·이동·품질·정책을 자동화해야 함
- **핵심 키워드 선정**: metadata harvesting, active metadata, knowledge graph, catalog, semantic layer, integration·virtualization, policy automation을 연계함
- **비교·구조·절차 배치**: Data Fabric·Data Mesh·Lakehouse를 중심 문제·구성 단위·책임 구조로 비교하고 연결부터 학습·최적화까지 전개함
- **전수 검수**: 모든 데이터를 한 저장소로 복제하는 제품으로 한정하지 않고 Data Mesh의 도메인 소유 모델을 대체하지 않는 기술적 통합 기반임을 일치시킴
- **Ⅲ·Ⅳ 도표 판단**: Ⅲ은 source·metadata graph·통합·정책 자동화의 관계를 세로형 정적 구조로 교정하고, Ⅳ는 실행 metadata가 다음 수집·판단으로 돌아가는 핵심 폐루프가 간결해 유지함

## Ⅰ. 개요

- **정의/개념**: 메타데이터로 분산 데이터 통합을 자동화
- **배경/필요성**: 이질 저장소·통합 방식의 탐색·정책 병목을 해소

### 쉽게 이해하기 (학습용)

- 모든 창고의 물품·경로·규칙을 공통 지도에 연결하여 운송과 출입을 자동 선택하는 물류망임

## Ⅱ. 특징

- active metadata가 추천·탐지·조치를 구동한다.
- 지식 그래프가 데이터 의미·관계를 연결한다.
- 복합 통합이 지연·비용·규제에 맞춰 흐름을 잇는다.
- 사람 승인이 고위험 자동화 오류를 통제한다.

### 쉽게 이해하기 (학습용)

- 지도가 배송 이력을 배워 최적 경로를 추천하되 중요 업무나 허가는 담당자가 확인하는 방식임

## Ⅲ. 아키텍처 및 구성요소

```text
분산 자산(DB/Lake/SaaS)
          ↓
메타데이터 수집
          ↓
지식 그래프·카탈로그
          ↓
통합/거버넌스/자동화
```

| 설계 요소 | 설명 |
|:---|:---|
| 메타데이터 수집 | 분산 저장소에서 스키마/계보/사용량 수집 |
| 카탈로그/의미 계층 | 자산을 공통 업무 용어로 정규화 |
| 지식 그래프 | 데이터, 관계, 용어 등을 연결해 추론 지원 |
| 통합 서비스 | 복제, 스트리밍, 가상화 등 방식 실행 |
| 거버넌스 엔진 | 메타데이터 기반 품질/보안 규칙 집행 |
| 자동화/조율 | 사용/변경 이력으로 정책 및 파이프라인 최적화 |

> 요약: 분산 메타데이터로 통합·정책 실행 자동화

### 쉽게 이해하기 (학습용)

- 여러 창고의 재고와 운송 규칙을 지도에 모으고, 그 지도가 실제 운송과 검사를 자동화하는 구조임

## Ⅳ. 원리 및 절차 흐름도

```text
데이터 수집
    ↓
그래프 구성
    ↓
품질/정책 평가
    ↓
통합 실행
    ↓
지속 학습/개선
```

| 절차 | 설명 |
|:---|:---|
| 데이터 수집 | 스키마, 사용량 등 메타데이터를 수집함 |
| 그래프 구성 | 자산과 업무 용어 관계를 연결함 |
| 품질/정책 평가 | 목적에 맞는 보안/품질 규칙을 결정함 |
| 통합 실행 | 최적 이동/조회 방식을 실행함 |
| 학습/개선 | 실행 결과로 추천 및 자동 조치를 개선함 |

> 요약: 메타데이터 기반 통합·정책의 폐루프 실행

### 쉽게 이해하기 (학습용)

- 지도로 경로와 허가를 결정한 뒤 배송 결과와 사고 결과를 지도에 되돌려 다음 배송을 개선함

## Ⅴ. 종류 및 비교

| 판단 기준 | Data Fabric | Data Mesh | Lakehouse |
|:---|:---|:---|:---|
| 핵심 특징 | 메타데이터 기반 통합 | 도메인 소유/확장성 | 저장 계층 통합 관리 |
| 적용 기준 | 그래프/자동화 서비스 | 도메인 제품/플랫폼 | 오브젝트 저장소/표 포맷 |
| 주요 위험 | 기술적 연결 계층 | 분산 소유 운영 모델 | 물리적/논리적 기반 |

> 요약: 기술 계층·운영 모델·저장 구조는 상호 보완

### 쉽게 이해하기 (학습용)

- 자동 물류망, 지역별 책임 조직, 대형 창고는 역할이 달라 함께 사용할 수 있음

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 금융사는 core banking·CRM·SaaS·lake의 고객 식별자와 업무 용어를 graph로 연결하고 민감도에 따라 virtual query 또는 승인된 복제로 고객 360을 제공함
- Data Mesh를 운영하는 유통사는 fabric의 catalog·lineage·policy automation을 셀프서비스 플랫폼에 넣어 주문·고객·재고 제품의 발견과 전역 규칙 집행을 지원함

## Ⅶ. 결론

- active metadata의 자동 조치와 승인 경계 설계

### 쉽게 이해하기 (학습용)

- 지도가 배송 결과를 배워도 위험한 경로 변경은 담당자가 승인함
