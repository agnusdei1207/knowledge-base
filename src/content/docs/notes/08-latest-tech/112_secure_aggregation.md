## 미리 알고가기

- 보안 집계: 서버가 개별 업데이트를 모른 채 합계만 계산함
- 단순 전송 암호화: 서버 메모리상 개별 값이 드러남
- 참가자 이탈: 이탈 시 drop-out 복구 메커니즘이 핵심임



## Ⅰ. 개요

- **정의/개념**: 개별 업데이트를 숨기고 합계만 복구하는 기술
- **배경/필요성**: 집계 서버의 참여자별 업데이트 노출 방지

### 쉽게 이해하기 (학습용)

- 참여자가 값을 서로 상쇄되는 마스크로 가려 보내면 서버에는 전체 합만 남습니다.

## Ⅱ. 특징

- 쌍별 마스크는 생존 참여자의 합에서 서로 상쇄된다.
- 비밀분산 자료로 이탈자의 남은 마스크를 제거한다.
- 공모 임계값을 넘으면 개별 기밀성이 깨질 수 있다.
- 값 은닉은 중독·최종 모델 누출을 막지 못한다.

### 쉽게 이해하기 (학습용)

- 서버에 합계만 보여도 참여 메타데이터와 완성 모델이 기억한 정보까지 자동으로 숨겨지지는 않습니다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 참여자·위협 임계값 | 집계를 완료할 최소 생존자 수와 허용할 서버·참여자 공모 범위 |
| 키·비밀분산 재료 | 마스크 해제와 이탈 복구용 비밀 조각 |
| 마스킹 업데이트 | 로컬 업데이트에 쌍별·개인 마스크를 더한 전송값 |
| 집계 서버 | 마스킹 업데이트와 복구 자료를 모아 허용된 합계를 계산하는 주체 |
| 마스크 해제·이탈 복구 정보 | 생존자·이탈자의 잔여 마스크 제거 정보 |

### 쉽게 이해하기 (학습용)

- 최소 생존자 수, 마스크·비밀분산 자료, 집계 서버와 이탈 복구 절차를 함께 설계해야 합니다.

## Ⅳ. 원리 및 절차 흐름도

```text
참여확정
  ↓
마스크분산
  ↓
마스킹업로드
  ↓
이탈식별
  ↓
해제자료구분
  ↓
합계복구
```

| 절차 | 설명 |
|:---|:---|
| 참여확정 | 참여자끼리 쌍별 비밀과 키를 설정함 |
| 마스크분산 | 마스크 복구 정보를 비밀분산함 |
| 마스킹업로드 | 로컬 업데이트에 마스크를 더해 전송함 |
| 이탈식별 | 생존자 수를 확인해 복구자료를 수집함 |
| 합계복구 | 생존자의 마스크를 제거해 합계만 얻음 |

- 서로 가림막을 나눠 합계만 복구함

### 쉽게 이해하기 (학습용)

- 참여자끼리 마스크 정보를 나누고 이탈자를 확인한 뒤 생존 참여자의 합만 복구합니다.

## Ⅴ. 종류 및 비교

| 적용 기준 | 전송 암호화 | 보안 집계 | 동형암호 |
|:---|:---|:---|:---|
| 서버가 보는 값 | 개별 값 복호화 | 마스킹된 값 | 암호문 집계 |
| 운영 조건 | 서버 신뢰 | 임계·이탈 복구 | 암호연산 비용 |
| 적용 환경 | 구간 보안 | 합계만 필요 | 암호문 연산 |

> 요약: 서버 신뢰 수준과 합계 복구 방식에 따라 선택함

### 쉽게 이해하기 (학습용)

- 전송 암호화는 서버가 개별 값을 보고 보안 집계와 동형암호는 서버에 보이는 값을 더 제한합니다.

## Ⅵ. 실무 사례

- 매 라운드 보안 집계로 개별 업데이트를 숨긴다.
- 허용 공모 수와 최소 생존자 수를 정해 적용한다.

### 쉽게 이해하기 (학습용)

- 개별 업데이트를 가려도 악성 참여자의 중독 업데이트까지 정상으로 만들지는 못합니다.

## Ⅶ. 결론

- 서버에 개별 값을 숨기고 합계만 필요할 때 적용함

### 쉽게 이해하기 (학습용)

- 개별 값 은닉과 업데이트 무결성, 최종 모델의 개인정보 누출은 서로 다른 통제로 관리해야 합니다.
