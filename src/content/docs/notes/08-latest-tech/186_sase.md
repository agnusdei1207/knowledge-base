## 미리 알고가기

- **SASE(Secure Access Service Edge)**: 네트워크와 보안 기능을 클라우드 서비스로 통합해 사용자·지점 접근을 보호하는 아키텍처
- **SD-WAN**: SASE에서 애플리케이션별 경로 선택과 품질을 담당하는 핵심 연결 요소
- **제로 트러스트**: SASE 보안의 핵심 원리로 위치와 관계없이 신원과 장치 맥락 기반의 지속적 검증 수행
- **분산 엣지**: 지연 시간 감소를 위해 사용자 인접 지역에서 정책을 집행하는 SASE 서비스 거점
- **SSE(Security Service Edge)**: SASE에서 연결 기능을 제외하고 보안 기능만을 집중적으로 제공하는 하위 집합
- **정책 통합**: 분산된 접속 경계에서 네트워크 경로와 보안 통제를 하나의 서비스 정책으로 조정함



## Ⅰ. 개요

사용자·장치·지점이 애플리케이션에 접근할 때 필요한 연결과 보안 기능을 정책 기반의 클라우드·분산 엣지 서비스로 통합하는 아키텍처임

- **정의/개념**: 광역 연결과 보안을 클라우드 서비스로 통합
- **배경/필요성**: 분산 사용자·지점의 일관된 근거리 통제를 확보
### 쉽게 이해하기 (학습용)

- **필요성**: 중앙 집중형 보안 방식의 지연과 정책 불일치 해소 필요

## Ⅱ. 특징

- 통합 정책이 경로와 보안 결정을 일치시킨다.
- SD-WAN이 지점·사용자·클라우드를 연결한다.
- 보안 서비스 결합이 접속별 위협을 통제한다.
- 분산 엣지가 지연을 줄이고 정책을 일관화한다.

### 쉽게 이해하기 (학습용)

- 어느 통신사 장비를 쓰느냐보다 사용자가 어디서 접속해도 같은 길 선택과 보안 규칙이 적용되는지가 중요함

## Ⅲ. 아키텍처 및 구성요소

```text
[User / Device] ─┐
[Branch / Site] ─┼→ [Access & Service Edge]
                        ├─ [SSE Security Functions]
                        ├─ [Connectivity / SD-WAN]
                        └→ [Web / SaaS / Private App / Cloud]
                        ↑
              [Identity / Policy / Telemetry]
```

| 설계 요소 | 설명 |
|:---|:---|
| 가입자 접속점 | 사용자·장치·지점 식별 및 에이전트·터널 연결 |
| 연결 서비스 | 애플리케이션별 경로·우선순위·품질·장애 우회 |
| 보안 서비스 | 제로 트러스트 접근·웹·방화벽·데이터 보안 |
| 분산 서비스 | 인접 위치 트래픽 수용·정책 집행·이중화 |
| 정책·관측 계층 | 신원·맥락 기반 정책 결정 및 통합 로그 관리 |

> 요약: 공통 신원·정책으로 보안·연결 서비스를 통합

### 쉽게 이해하기 (학습용)

- 사용자와 지점은 가까운 서비스 거점에 들어가 같은 신원 규칙으로 검사받고 목적지와 품질에 맞는 길로 전달됨

## Ⅳ. 원리 및 절차 흐름도


```text
접속요청
   ↓
거점선택
   ↓
맥락분류
   ↓
정책결정
   ↓
보안집행
   ↓
경로전달
```

| 절차 | 설명 |
|:---|:---|
| 1. 접속요청 | 트래픽을 에이전트·터널·엣지로 거점에 전달함 |
| 2. 거점선택 | 사용자와 앱에 적합한 서비스 거점을 선택함 |
| 3. 맥락분류 | 신원·장치·앱·데이터·위협 맥락을 분류함 |
| 4. 정책결정 | 접근 통제·품질·경로·인증 정책을 결정함 |
| 5. 보안집행 | 목적지별 검사와 보안 기능을 연속 적용함 |
| 6. 경로전달 | 가용성·지연 반영 경로로 트래픽을 전달함 |

> 요약: 신원·맥락으로 보안·경로를 연속 결정

### 쉽게 이해하기 (학습용)

- 요청의 사람과 기기와 목적지를 확인한 뒤 필요한 검사와 빠른 길을 함께 정하고 길이 막히거나 위험해지면 다시 선택함

## Ⅴ. 종류 및 비교

| 판단 기준 | SASE | 보안 서비스 엣지 | 기존 허브 경유 방식 |
|:---|:---|:---|:---|
| 핵심 특징 | 연결·보안을 분산 엣지에서 통합 | 클라우드 보안만 서비스화 | 중앙 경계로 트래픽을 모아 검사 |
| 적용 기준 | 분산 사용자·지점의 직접 접속 | 기존 WAN을 두고 보안만 통합 | 중앙 경계·업무 위치가 안정적 |
| 주요 위험 | 제공자 종속·거점 품질 편차 | 연결·보안 정책의 분리 | 백홀 지연·중앙 장애 집중 |

> 요약: SASE는 SSE와 연결 서비스를 결합한 아키텍처

### 쉽게 이해하기 (학습용)

- SSE가 보안 검색대라면 SASE는 검색대에 목적지별 길 안내와 지점 간 연결까지 묶은 서비스임

## Ⅵ. 실무 사례

1. **다지점 매장의 SaaS 직접 접속**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

2. **원격 사용자와 사설 애플리케이션 통합**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

### 쉽게 이해하기 (학습용)
