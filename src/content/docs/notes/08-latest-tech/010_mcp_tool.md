## 미리 알고가기

- **모델 컨텍스트 프로토콜 (Model Context Protocol, MCP)**: 호스트와 서버의 기능·컨텍스트 교환 규격
- **인공지능 (Artificial Intelligence, AI)**: 도구 사용을 제안하고 결과를 활용하는 애플리케이션
- **대규모 언어 모델 (Large Language Model, LLM)**: 도구 호출 인자를 생성하는 모델
- **제이에스온 (JavaScript Object Notation, JSON)**: 도구 인자를 구조화하는 데이터 형식
- **JSON 스키마 (JSON Schema)**: 도구 입력·출력 구조를 정의하는 규격
- **호출 식별자 (Identifier, ID)**: 도구 호출과 결과를 연결하는 값
- **부작용 (Side Effect)**: 실행으로 외부 시스템 상태가 바뀌는 현상
- **인간 개입 (Human-in-the-Loop, HITL)**: 고위험 호출을 사람이 승인하는 통제
- **프롬프트 주입 (Prompt Injection)**: 악성 지시로 도구 호출을 유도하는 공격

## Ⅰ. 개요
- **정의/개념**: 서버가 스키마로 노출하는 모델 호출 기능
- **배경/필요성**: 업무 기능을 공통 인자·결과 계약으로 실행

### 쉽게 이해하기 (학습용)
- AI가 설명서를 보고 필요한 기계를 호출하는 기능임

## Ⅱ. 특징
- tools/list가 이름·설명·스키마를 선언한다
- tools/call이 선택한 도구를 호출한다
- 서버가 인자·권한·부작용을 검증한다
- 결과는 콘텐츠·오류 상태로 반환한다
- 목록 변경 시 호스트가 갱신·동의를 확인한다

### 쉽게 이해하기 (학습용)
- 도구 설명서를 보고 호출하지만 위험한 일은 서버와 사람이 한 번 더 확인함

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    H[MCP 호스트]
    C[MCP 클라이언트]
    subgraph S[MCP 서버 경계]
        D[도구 명세]
        V[입력 검증기]
        P[정책 집행기]
        E[실행기]
        R[결과 처리기]
        D -->|스키마 제공| V
        V -->|검증 인자| P
        P -->|허용 호출| E
        E -->|실행 결과| R
    end
    H -->|호출 제안·승인| C
    C -->|도구 목록·호출| D
    R -->|결과·오류| C
```

| 설계 요소 | 설명 |
|:---|:---|
| 도구 명세 | 이름·설명·입력 스키마를 제공 |
| 입력 검증기 | 인자 구조와 값의 유효성을 검사 |
| 정책 집행기 | 권한·동의·부작용 정책을 적용 |
| 실행기 | 허용된 도구를 백엔드에서 실행 |
| 결과 처리기 | 콘텐츠·오류를 클라이언트로 반환 |

> 요약: 명세·검증·정책을 거쳐 도구를 실행

### 쉽게 이해하기 (학습용)
- 설명서와 검사 담당자를 거쳐 허용된 명령만 실행하고 결과를 돌려줌

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant H as MCP 호스트
    participant C as MCP 클라이언트
    participant S as MCP 서버
    participant B as 백엔드
    C->>S: 기능목록조회
    S-->>C: 도구목록
    H->>C: 호출제안
    opt 승인 필요
        C->>H: 승인요청
        H-->>C: 승인결과
    end
    C->>S: 도구호출
    S->>S: 입력검증
    S->>B: 백엔드실행
    B-->>S: 실행결과
    S-->>C: 도구결과
    C-->>H: 결과전달
```

| 절차 | 설명 |
|:---|:---|
| 기능목록조회 | 사용 가능한 도구를 요청 |
| 도구목록 | 도구명·설명·스키마를 수신 |
| 호출제안 | 모델이 도구와 인자를 제안 |
| 승인요청 | 고위험 호출의 사용자 승인을 요청 |
| 승인결과 | 호출 허용·거부를 반환 |
| 도구호출 | 도구명과 인자를 서버에 전송 |
| 입력검증 | 스키마와 권한을 검사 |
| 백엔드실행 | 허용된 기능을 실행 |
| 실행결과 | 백엔드 결과를 서버에 반환 |
| 도구결과 | 콘텐츠와 오류 상태를 반환 |
| 결과전달 | 도구 결과를 모델 입력에 반영 |

> 요약: 제안·승인·검증 후 도구 결과를 반영

### 쉽게 이해하기 (학습용)
- AI가 도구를 고르면 사람이 승인하고 서버가 검사한 뒤 실행함

## Ⅴ. 종류 및 비교

| 판단 기준 | MCP Tool | MCP Resource |
|:---|:---|:---|
| 제어 주체 | 모델·호스트 | 호스트·애플리케이션 |
| 인터페이스 | 이름·inputSchema·tools/call | URI·resources/read |
| 결과 성격 | 실행 결과·오류 | 컨텍스트 데이터 |
| 적용 기준 | 외부 기능을 실행할 때 | 읽을 근거가 필요할 때 |

> 요약: 실행은 Tool, 컨텍스트는 Resource

### 쉽게 이해하기 (학습용)
- 도구는 일을 시키고 리소스는 필요한 자료를 읽는 기능임

## Ⅵ. 실무 사례
- 재시작 도구는 대상 ID 검증·승인 후 호출

### 쉽게 이해하기 (학습용)
- 서버를 다시 켜는 명령은 대상을 확인하고 사람 허락 뒤 실행함

## Ⅶ. 결론
- 부작용·민감도에 따라 도구 권한과 사용자 승인을 적용

### 쉽게 이해하기 (학습용)
- 위험한 도구일수록 권한을 좁히고 사람 확인을 거침
