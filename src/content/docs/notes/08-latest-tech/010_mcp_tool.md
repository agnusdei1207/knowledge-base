## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **모델 컨텍스트 프로토콜(Model Context Protocol, MCP)**: 호스트와 서버의 기능•컨텍스트 교환을 표준화한 프로토콜로 정의된다.
- **모델 컨텍스트 프로토콜 도구(Model Context Protocol Tool, MCP Tool)**: 구조화된 인자로 외부 시스템의 행동을 실행하는 MCP 기능을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **대규모 언어 모델(Large Language Model, LLM)**: 문맥과 도구 명세를 바탕으로 호출할 도구와 인자를 생성하는 모델로 정의된다.

</details>

- 정의/개념: MCP 서버가 외부 행동을 공개하는 **MCP Tool**
- 배경/필요성: 함수별 인자•권한 계약 차이로 LLM이 행동을 일관되게 호출하기 어려움.

#### 한줄 요약
- **LLM**이 도구 명세에 맞춘 구조화 인자로 행동 호출

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **자바스크립트 객체 표기법 스키마(JavaScript Object Notation Schema, JSON Schema)**: 도구 입력•출력 구조와 자료형•필수 필드를 정의하는 규격이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **부작용(Side Effect)**: 도구 실행으로 외부 시스템의 데이터나 상태가 바뀌는 현상을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **선택 축(Selection Axis)**: 목표•문맥에 맞는 도구와 인자를 모델이 제안하는 기능 영역으로 정의된다.
- **계약 축(Contract Axis)**: tools/list•tools/call과 JSON Schema로 호출 계약을 표준화하는 기능 영역으로 정의된다.
- **통제 축(Control Axis)**: 호스트 동의와 서버 재검증으로 부작용을 제한하는 기능 영역을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- **선택 축**: 목표•문맥별 도구•인자 제안
- **계약 축**: tools/list•tools/call•JSON Schema 표준화
- **통제 축**: 호스트 동의•서버 재검증으로 부작용 통제

#### 한줄 요약
- **JSON Schema•통제 축**으로 인자•고위험 행동 제한

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **정책 집행기(Policy Enforcer)**: 권한•사용자 동의•부작용 허용 범위를 확인해 실행 여부를 결정하는 구성요소를 지칭한다.
- **백엔드 도구(Backend Tool)**: MCP 서버가 검증 후 실제 외부 시스템에서 실행하는 기능을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **모델 컨텍스트 프로토콜 서버(Model Context Protocol Server, MCP Server)**: 도구 명세를 제공하고 검증된 백엔드 행동을 실행하는 구성요소를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

- **입력 검증기•정책 집행기** 확인 후 백엔드 호출

```text
                         [정책 집행기]
                        /             \
              [입력 검증기]         [실행기]
                    |                   |
                [도구 명세]        [결과 처리기]
```

선의 의미: 정책 집행기는 입력 검증기와 실행기의 권한 경계를 통제하고, 입력 검증기는 도구 명세를 기준으로 인자를 검사하며, 실행기의 결과는 결과 처리기가 구조화함.

| 구성요소 | 책임 |
|:---|:---|
| 도구 명세 | **JSON Schema** 기반 이름•설명•입력 계약을 제공함 |
| 입력 검증기 | 인자 구조•값 유효성을 검사함 |
| 정책 집행기 | **정책 집행기**가 권한•동의•부작용 정책을 적용함 |
| 실행기 | 허용된 **백엔드 도구**를 실행함 |
| 결과 처리기 | 구조화 콘텐츠•오류를 반환함 |

#### 한줄 요약
- **정책 집행기•입력 검증기**를 거쳐 허용 도구 실행

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **인간 개입(Human-in-the-Loop, HITL)**: 고위험 호출을 사람이 검토•승인하는 통제로 정의된다.
- **tools/list•tools/call**: MCP 서버의 도구 명세를 조회하고 선택한 도구를 실행하는 표준 요청으로 정의된다.
- **모델 컨텍스트 프로토콜 호스트(Model Context Protocol Host, MCP Host)**: 사용자 동의와 정책에 따라 도구 호출을 중개하는 AI 애플리케이션을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **도구 목록•입력 스키마 요청(Tool List Request)**: 사용 가능한 행동과 인자 계약을 탐색하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **선택 가능한 도구 명세 제공(Tool Spec Provision)**: 서버가 허용 기능의 이름•설명•스키마를 반환하는 단계로 정의된다.
- **승인된 도구명•구조화 인자 확정(Tool Confirmation)**: 모델 제안과 사람 승인 결과로 호출 내용을 정하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **tools/call 요청(tools/call Request)**: 도구명과 JSON 구조화 인자를 서버에 전송하는 단계를 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **권한•입력 검증 후 백엔드 실행(Backend Execution)**: 서버가 주체•인자•정책을 재검증해 허용 행동만 수행하는 단계를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

- **MCP Host•Server** 간 JSON 인자와 HITL 승인 교환

```text
사용자
   │ 목표•외부 행동 요청
   ▼
MCP 호스트•클라이언트
   │ 1. 도구 목록•입력 스키마 요청
   ▼
MCP 서버
   │ 2. 선택 가능한 도구 명세 제공
   ▼
MCP 호스트•클라이언트
   ├───────────────────┐
   │ 고위험 도구이면   │◄──── 사용자 승인
   └─────────┬─────────┘
   │ 3. 승인된 도구명•구조화 인자 확정
   │ 4. tools/call 요청
   ▼
MCP 서버
   │ 5. 권한•입력 검증 후 백엔드 실행
   ▼
백엔드
   │ 실행 결과•오류 반환
   ▼
MCP 서버
   │ 출처가 구분된 구조화 결과 반환
   ▼
MCP 호스트•클라이언트
   │ 실행 결과 제공
   ▼
사용자
```

### 동작 원리

1. **도구 목록•입력 스키마 요청**: **tools/list•tools/call** 계약에서 사용 가능한 행동•인자를 탐색함.
2. **선택 가능한 도구 명세 제공**: 허용 기능의 명세를 반환함.
3. **승인된 도구명•구조화 인자 확정**: 모델 제안•HITL 결과를 반영함.
4. **tools/call 요청**: 도구명과 JSON 구조화 인자를 전송함.
5. **권한•입력 검증 후 백엔드 실행**: 허용된 행동만을 수행함.

#### 한줄 요약
- **도구•인자 승인** 후 서버 재검증•실행

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **Resource**: 애플리케이션이 제공하고 모델이 문맥으로 읽는 데이터를 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **Tool**: 모델이 구조화된 인자로 호출해 외부 행동을 수행하는 기능을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **Prompt**: 사용자가 선택해 작업 메시지와 입력 틀을 만드는 기능을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **모델 컨텍스트 프로토콜 리소스(Model Context Protocol Resource, MCP Resource)**: URI로 식별한 읽기 문맥을 제공하는 MCP 기능으로 정의된다.
- **통합 자원 식별자(Uniform Resource Identifier, URI)**: 리소스를 고유하게 가리키는 주소 표기로 정의된다.

</details>

- **Resource•Tool•Prompt**를 조회•행동•작업 틀로 구분

| 비교 기준 | Resource | Tool | Prompt |
|:---|:---|:---|:---|
| 적용 기준 | **Resource**는 문맥 데이터를 제공함 | **Tool**은 외부 기능을 실행함 | **Prompt**는 사용자 작업 틀을 제공함 |
| 핵심 특징 | 앱 제어•**URI** 조회를 수행함 | 모델 제어•스키마를 호출함 | 사용자 제어•메시지를 생성함 |
| 한계 | 직접 행동 수행 불가임 | **부작용**•권한 위험이 존재함 | 사용자 선택•입력이 필요함 |

> 요약: 문맥 조회에는 **Resource**, 행동에는 **Tool**, 작업 틀에는 **Prompt**를 적용함.

#### 한줄 요약
- 외부 행동은 **Tool**, 읽기 문맥은 **Resource**

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **프롬프트 주입(Prompt Injection)**: 비신뢰 콘텐츠의 악성 지시로 도구 호출을 유도하는 공격을 지칭한다.
- **최소권한(Least Privilege)**: 도구에 업무 수행에 필요한 최소 범위의 권한만 부여하는 원칙을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 과도한 도구 호출로 행동 범위 확대 | 허용 목록•**최소권한**을 적용함 | 모델 행동 범위를 제한함 |
| **프롬프트 주입**으로 무단 상태 변경 | 비신뢰 명령 분리•**HITL** 승인을 수행함 | 간접 권한 상승을 방지함 |
| 대상•인자 오류로 잘못된 **부작용** | 현재 상태•업무 규칙을 재검증함 | 오실행•책임 공백을 축소함 |

#### 한줄 요약
- 상태 변경은 **대상 검증•HITL** 승인 후 실행

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **도구 통제 결정(Tool Control Decision)**: 외부 시스템 변경이 필요한 작업은 허용 목록과 최소 권한으로 호출 범위를 좁히고 고위험은 HITL 승인을 적용하는 결정을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

- 외부 행동은 **MCP Tool**, 읽기 문맥은 **Resource** 선택

#### 한줄 요약
- **행동 부작용•위험도**에 따라 최소 권한•HITL 결정
