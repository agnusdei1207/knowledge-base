## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **함수 호출(Function Calling)**: 모델이 자연어 의도를 함수명과 구조화된 인자로 변환하여 호스트에 실행 요청하는 연계 방식. 시스템의 자율적 판단과 외부 시스템 상호작용을 매개하는 표준 인터페이스.

</details>

- 개념: 자연어 의도를 함수명·구조화 인자로 변환하는 연계 방식. 단순 답변 생성을 넘어 외부 시스템에 구체적 행위를 위임하는 표준 인터페이스.
- 배경: 함수 선택, 인자 타당성, 실행 권한, 부작용을 자연어만으로 검증 불가. 안전한 자동화를 위한 구조화된 호출 계약 필수.

#### 한줄 요약
- **함수 호출**에서 모델은 함수•인자를 제안하고 호스트는 검증•실행 체계 적용

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **구조화 출력(Structured Output)**: 데이터 스키마에 맞춰 모델 응답을 생성하여 다운스트림 시스템이 즉시 처리하도록 하는 기능.
- **JSON 스키마(JSON Schema)**: 인자의 자료형·필수 필드·허용 범위를 제한하는 명세. 자동화된 런타임 형식 검증으로 안정성 확보.
- **형식 축(Format Axis)**: 함수 설명과 JSON 스키마로 함수명·인자 구조를 선언적으로 규정하는 기능 영역.
- **실행 축(Execution Axis)**: 호출 식별자(Call ID)로 실행과 재시도 결과를 연결하고 호스트가 검증·실행하는 기능 영역.

</details>

- **형식 축**: 함수 설명과 **JSON 스키마** 기반으로 함수•인자 구조를 제한하여, 모델이 호출 가능한 함수 목록과 각 함수의 인자 형식을 사전에 정확히 인지하도록 강제한다. 이는 실무 환경에서의 유연한 대응과 지속적 최적화를 지원한다.
- **도구 선택 정책(Tool Choice Policy)** 기반 자동•필수•금지 호출 제어가 핵심이며, 모델이 함수를 호출할지 여부와 어떤 함수를 선택할지를 정책 수준에서 통제한다. 이는 전통적 방식과의 핵심 차별점으로서 실질적인 업무 가치를 창출한다.
- **실행 축**: 호출 ID로 병렬 호출과 재시도 결과를 연결해 호스트가 검증하도록 하며, 다수의 함수 호출이 동시에 발생할 때 각 요청과 결과를 정확히 매핑하고 실패한 호출의 재시도를 안전하게 관리한다. 이는 실무 환경에서의 유연한 대응과 지속적 최적화를 지원한다.

#### 한줄 요약
- **JSON 스키마**는 형식을 제한하나 값•부작용은 미보장이 핵심 구조 구현

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **함수 스키마(Function Schema)**: 함수의 목적과 인자 이름, 자료형, 필수 여부, 허용 범위를 선언하는 계약을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다. 모델이 함수의 의미와 사용법을 이해하는 데 사용하는 표준화된 명세 형식이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 호스트 실행기가 검증된 함수 요청을 실제 업무 기능과 연결하는 인터페이스이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 함수 호출 계약의 최종 실행 지점으로, 비즈니스 로직과 시스템 자원에 접근하는 통로를 제공한다.
- **호출 식별자(Call ID)**: 병렬•재시도 함수 요청과 각 실행 결과를 정확히 연결하는 고유 값이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 다중 호출 환경에서 응답 매핑 오류를 방지하고 재시도 시 중복 실행을 식별하는 데 핵심적인 역할을 한다.

</details>

```text
                  [함수 명세]
                       |
                  [모델 라우터]
                       |
                  [검증•정책]
                       |
                 [호스트 실행기]
```

선의 의미: 함수 명세와 모델 라우터의 제안이 검증•정책 경계를 통과해 호스트 실행기에 연결되는 함수 호출 계약 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 함수 명세 | JSON 스키마 기반 함수 목록과 인자 규격 선언 |
| 모델 라우터 | 사용자 의도 기반 함수·인자·병렬 호출 JSON 제안 |
| 검증·정책 | 형식 적합성, 인자 범위, 권한, 부작용 종합 검사 |
| 호스트 실행기 | 검증된 요청을 API 함수·Call ID와 연결 및 결과 반환 |

#### 한줄 요약
- **함수 스키마**와 호스트 검증•실행 결과를 호출 계약으로 연결 체계 적용

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **함수명•설명•인자 스키마 제공(Schema Provision)**: 선택 가능한 함수와 필수 필드, 자료형, 허용 범위를 제시하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 모델이 호출 가능 범위를 학습하고 적절한 함수를 선택하는 토대가 된다.
- **함수명•인자•호출 ID 제안(Function Proposal)**: 자연어 요청을 구조화된 실행 의도로 변환하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 모델의 추론 결과를 시스템이 처리 가능한 계약 형태로 정형화한다.
- **형식•값•권한 검증 후 실행(Verified Execution)**: 원문 의도, 업무 규칙, 권한 정책과 대조해 승인된 함수를 호출하는 단계를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다. 모델의 제안을 무조건 신뢰하지 않고 호스트가 안전성을 재확인하는 게이트 역할을 수행한다.
- **실행 결과•오류 반환(Execution Return)**: 함수 출력과 실패 원인을 호스트에 전달하는 단계이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 성공 데이터뿐 아니라 오류 코드와 메시지를 함께 제공하여 후속 처리의 분기 결정을 지원한다.
- **호출 ID와 결과 연결(ID/Result Linking)**: 병렬 호출과 재시도 결과를 올바른 요청에 결합하는 단계를 지칭한다. 다수의 동시 호출이나 실패 후 재호출 시에도 각 결과를 원래의 요청과 정확히 매핑하여 응답의 일관성을 보장한다.

</details>

```text
호스트
   │ 1. 함수명·설명·인자 스키마 제공
   ▼
모델
   │ 2. 함수명·인자·호출 ID 제안
   ▼
호스트
   │ 3. 형식·값·권한 검증 후 실행
   ▼
업무 함수
   │ 4. 실행 결과·오류 반환
   ▼
호스트
   │ 5. 호출 ID와 결과 연결
   ▼
모델
```

### 동작 원리

1. **함수명•설명•인자 스키마 제공**: 호스트가 선택 가능한 함수 목록과 각 함수의 필수 필드, 자료형, 허용 값 범위를 모델에 제시하여 호출 가능 범위를 사전에 정의함.
2. **함수명•인자•호출 ID 제안**: 모델이 자연어 요청을 해석하여 적절한 함수명과 인자, 그리고 고유 **Call ID**를 포함한 구조화된 실행 의도로 변환함.
3. **형식•값•권한 검증 후 실행**: 호스트가 원문 의도, 업무 규칙, 권한 정책을 종합적으로 대조하여 승인된 함수만을 실제 실행함.
4. **실행 결과•오류 반환**: 업무 함수가 실행 결과를 출력하거나 실패 시 오류 코드와 원인을 호스트에 전달함.
5. **호출 ID와 결과 연결**: 호스트가 병렬 호출과 재시도 결과를 해당 **Call ID**와 정확히 결합하여 모델에 최종 응답을 구성함.

#### 한줄 요약
- **형식·값·권한 검증 후 실행**하고 **호출 ID와 결과 연결**로 응답 결합 체계 적용.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **병렬 함수 호출(Parallel Function Calling)**: 데이터 의존성이 없는 여러 함수 요청을 모델이 한 번의 응답에 함께 제안하여 호스트가 동시에 처리하게 하는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다. 순차 호출 대비 전체 지연 시간을 크게 단축하고 시스템 처리량을 높인다.

</details>

| 판단 기준 | 함수 호출 | 프롬프트 기반 JSON | 제약형 구조 출력 |
|:---|:---|:---|:---|
| 적용 기준 | **함수 호출**은 외부 함수 실행 의도가 명확할 때 적용함 | 프롬프트 JSON은 형식 유도만이 필요할 때 사용함 | **구조화 출력**은 실행 없이 스키마 일치만 필요할 때 적용함 |
| 핵심 특징 | 함수명•인자•**Call ID**를 반환하여 실행까지 연결함 | 프롬프트로 JSON 형식을 비공식적으로 유도함 | **구조화 출력**의 스키마와 정확히 일치하는 응답을 생성함 |
| 한계 | 값의 의미적 정확성, 권한, 실행 결과는 별도 검증이 필요함 | 모델이 형식을 위반할 가능성이 상존함 | 외부 함수 실행 의미가 없어 실제 업무 시스템 연동은 불가함 |

> 요약: **함수 호출**은 실행 의도를, **구조화 출력**은 형식을 구조화한다.

#### 한줄 요약
- 데이터 의존성이 없으면 **병렬 함수 호출**로 실행 시간을 줄인 기전 적용

## Ⅵ. 실무 고려사항 및对策

<details>
<summary>핵심 용어</summary>

- **도구 선택 정책(Tool Choice Policy)**: 함수 호출을 자동•필수•금지하거나 특정 함수로 제한하여 모델의 호출 범위를 통제하는 정책이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다. 모델이 임의로 함수를 호출하거나 부적절한 함수를 선택하는 것을 방지하는 통제 수단이다.
- **멱등성(Idempotency)**: 같은 함수 요청을 여러 번 실행해도 추가 부작용 없이 동일한 최종 상태에 도달하는 성질을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다. 네트워크 재시도나 중복 호출 시에도 시스템의 일관성을 유지하는 핵심 보장 메커니즘이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스키마는 맞지만 값이 틀린 의미상 오류(Semantic Error) | 사용자 원문 의도•업무 데이터•인자 허용 범위를 교차 대조함 | 잘못된 인자 실행을 사전에 차단함 |
| 재시도로 발생하는 주문 중복 실행 | **Call ID**와 **멱등성** 키를 활용해 기존 결과를 재사용함 | 중복 업무 부작용 발생을 방지함 |
| 상태 변경 함수의 권한 우회 시도 | **도구 선택 정책**과 읽기•쓰기 함수 분리 및 명시적 사용자 승인을 적용함 | 실제 업무 시스템의 권한 경계를 보호함 |

#### 한줄 요약
- **멱등성**과 인자•원문•권한을 검증한 뒤 주문 API를 호출 체계 적용

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>


</details>

- 외부 실행 의도는 **함수 호출**로 구조화하고 값•권한•멱등성은 호스트가 검증하여, 모델의 제안과 시스템의 실행 사이의 책임 경계를 명확히 분리하는 안전 계약 체계 적용이 필수적이다.

#### 한줄 요약
- **함수 스키마**에 맞는 인자를 호스트가 검증·승인한 뒤 실행하는 안전 계약 체계 적용.
