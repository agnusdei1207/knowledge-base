## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **함수 호출(Function Calling)**: 모델이 자연어 의도를 함수명과 구조화된 인자로 변환하여 호스트에 실행 요청하는 연계 방식. 시스템의 자율적 판단과 외부 시스템 상호작용을 매개하는 표준 인터페이스.

</details>

- 개념: 자연어 의도를 함수명•구조화 인자로 변환하는 **실행 계약**
- 배경/필요성: 사용자의 모호한 자연어 명령을 기존 소프트웨어 API나 데이터베이스 쿼리로 직접 전달할 경우, 데이터 타입 불일치, 필수 인자 누락, 문법 파싱 오류로 인해 시스템 장애가 빈번히 발생하고, 프롬프트 엔지니어링만으로 JSON 출력을 유도하는 방식은 런타임 환각 및 형식 파괴를 방어하지 못하는 한계가 발생함에 따라, LLM의 디코딩 단계에서 사전에 정의된 JSON Schema에 따라 함수명과 타입 안전 인자만을 강제로 생성하는 함수 호출(Function Calling) 구조화 인터페이스를 도입하여 **자연어 의도의 결정론적(Deterministic) 구조화 데이터 변환, 백엔드 API와의 즉각적이고 안정적인 상호운용성 확보 및 다중·병렬 함수 호출(Parallel Function Calling)을 통한 시스템 처리 지연 최소화**를 달성할 필요

#### 한줄 요약
- **함수•인자 제안**을 스키마로 구속하면 호출 신뢰성은 오르지만 스키마 밖 요구는 표현할 수 없으므로, 표현력을 줄여 검증 가능성을 사는 선택이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **구조화 출력(Structured Output)**: 데이터 스키마에 맞춰 모델 응답을 생성하여 다운스트림 시스템이 즉시 처리하도록 하는 기능.
- **JSON 스키마(JSON Schema)**: 인자의 자료형·필수 필드·허용 범위를 제한하는 명세. 자동화된 런타임 형식 검증으로 안정성 확보.
- **형식 축(Format Axis)**: 함수 설명과 JSON 스키마로 함수명·인자 구조를 선언적으로 규정하는 기능 영역.
- **실행 축(Execution Axis)**: 호출 식별자(Call ID)로 실행과 재시도 결과를 연결하고 호스트가 검증·실행하는 기능 영역.

</details>

- **형식 축**: JSON 스키마로 함수•인자 구조 제한
- **도구 선택 정책**: 자동•필수•금지 호출 제어
- **실행 축**: Call ID로 병렬•재시도 결과 연결

#### 한줄 요약
- **JSON 스키마** 기반 형식만 보장하고 값•부작용은 미보장

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **함수 스키마(Function Schema)**: 함수의 목적과 인자 이름, 자료형, 필수 여부, 허용 범위를 선언하는 계약을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다. 모델이 함수의 의미와 사용법을 이해하는 데 사용하는 표준화된 명세 형식이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 호스트 실행기가 검증된 함수 요청을 실제 업무 기능과 연결하는 인터페이스. 함수 호출 계약의 최종 실행 지점으로, 비즈니스 로직과 시스템 자원에 접근하는 통로를 제공한다.
- **호출 식별자(Call ID)**: 병렬•재시도 함수 요청과 각 실행 결과를 정확히 연결하는 고유 값. 다중 호출 환경에서 응답 매핑 오류를 방지하고 재시도 시 중복 실행을 식별하는 데 핵심적인 역할을 한다.

</details>

```text
                  [함수 명세]
                       |
                  [모델 라우터]
                       |
                  [검증•정책]
                       |
                 [호스트 실행기]
```

선의 의미: 함수 명세와 모델 라우터의 제안이 검증•정책 경계를 통과해 호스트 실행기에 연결되는 함수 호출 계약 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 함수 명세 | 함수 목록과 **JSON 인자 스키마** 선언 |
| 모델 라우터 | 의도 기반 **함수·인자·병렬 호출** 제안 |
| 검증·정책 | 형식·값·권한·**부작용 검사** |
| 호스트 실행기 | API·Call ID 연결과 **실행 중개** |

#### 한줄 요약
- **함수 스키마•호스트 검증** 실행 계약으로 연결

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **함수명•설명•인자 스키마 제공(Schema Provision)**: 선택 가능한 함수와 필수 필드, 자료형, 허용 범위를 제시하는 단계. 모델이 호출 가능 범위를 학습하고 적절한 함수를 선택하는 토대가 된다.
- **함수명•인자•호출 ID 제안(Function Proposal)**: 자연어 요청을 구조화된 실행 의도로 변환하는 단계. 모델의 추론 결과를 시스템이 처리 가능한 계약 형태로 정형화한다.
- **형식•값•권한 검증 후 실행(Verified Execution)**: 원문 의도, 업무 규칙, 권한 정책과 대조해 승인된 함수를 호출하는 단계이다. 모델의 제안을 무조건 신뢰하지 않고 호스트가 안전성을 재확인하는 게이트 역할을 수행한다.
- **실행 결과•오류 반환(Execution Return)**: 함수 출력과 실패 원인을 호스트에 전달하는 단계. 성공 데이터뿐 아니라 오류 코드와 메시지를 함께 제공하여 후속 처리의 분기 결정을 지원한다.
- **호출 ID와 결과 연결(ID/Result Linking)**: 병렬 호출과 재시도 결과를 올바른 요청에 결합하는 단계를 지칭한다. 다수의 동시 호출이나 실패 후 재호출 시에도 각 결과를 원래의 요청과 정확히 매핑하여 응답의 일관성을 보장한다.

</details>

```text
호스트
   │ 1. 함수명•설명•인자 스키마 제공
   ▼
모델
   │ 2. 함수명•인자•호출 ID 제안
   ▼
호스트
   │ 3. 형식•값•권한 검증 후 실행
   ▼
업무 함수
   │ 실행 결과·오류 반환
   ▼
호스트
   │ 4. 호출 ID와 결과 연결
   ▼
모델
```

### 동작 원리

1. 함수명•설명•인자 스키마 제공: 호출 범위 정의
2. 함수명•인자•호출 ID 제안: 실행 의도 구조화
3. 형식•값•권한 검증 후 실행: 승인 함수만 실행
4. 호출 ID와 결과 연결: 병렬·재시도 **결과 결합**

#### 한줄 요약
- **형식•값•권한 검증** 후 Call ID로 결과 결합

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **병렬 함수 호출(Parallel Function Calling)**: 데이터 의존성이 없는 여러 함수 요청을 모델이 한 번의 응답에 함께 제안하여 호스트가 동시에 처리하게 하는 방식. 순차 호출 대비 전체 지연 시간을 크게 단축하고 시스템 처리량을 높인다.

</details>

| 구분 | 함수 호출 | 프롬프트 기반 JSON | 제약형 구조 출력 |
|:---|:---|:---|:---|
| 적용 기준 | **외부 함수 실행 의도** | **JSON 형식 유도** | **스키마 일치 출력** |
| 핵심 특징 | 함수명·인자·**Call ID** | 프롬프트 기반 **비공식 형식** | 스키마 강제 **구조화 출력** |
| 한계 | **값·권한·결과** 별도 검증 | **형식 위반** 가능성 | **외부 함수 실행** 불가 |

> 요약: **함수 호출** 실행 의도를, **구조화 출력** 형식을 구조화한다.

#### 한줄 요약
- 데이터 독립 호출은 **병렬 함수 호출** 기반 지연 단축

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **도구 선택 정책(Tool Choice Policy)**: 함수 호출을 자동•필수•금지하거나 특정 함수로 제한하여 모델의 호출 범위를 통제하는 정책. 모델이 임의로 함수를 호출하거나 부적절한 함수를 선택하는 것을 방지하는 통제 수단이다.
- **멱등성(Idempotency)**: 같은 함수 요청을 여러 번 실행해도 추가 부작용 없이 동일한 최종 상태에 도달하는 성질이다. 네트워크 재시도나 중복 호출 시에도 시스템의 일관성을 유지하는 핵심 보장 메커니즘이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스키마는 맞지만 값이 틀린 의미 오류 | 원문·업무 데이터·**인자 범위 대조** | **잘못된 실행** 차단 |
| 재시도에 따른 주문 중복 | **Call ID·멱등성 키**로 결과 재사용 | **중복 부작용** 방지 |
| 상태 변경 함수의 권한 우회 | 읽기·쓰기 분리와 **명시적 승인** | **권한 경계** 보호 |

#### 한줄 요약
- **멱등성•인자•권한** 검증 후 상태 변경 API 호출

## Ⅶ. 결론

- 비정형 자연어 의도를 정형화된 소프트웨어 실행 계약으로 변환하여 생성형 AI와 레거시 엔터프라이즈 시스템 간의 완벽한 가교 역할을 수행하는 **구조화 인터페이스 표준(Function Calling / JSON Schema & Structured Outputs / Parallel Tool Calls & Call ID / Idempotency & RBAC)의 핵심 기술**로 확고히 자리 잡았으며, 제약 디코딩(Constrained Decoding) 기반 문법 강제(Grammar-based Sampling) 기술로 더욱 정밀화되는 가운데, 실무 백엔드 API 연동 시스템 설계 시에는 **인자 타입·범위·필수 속성을 엄격히 정의한 JSON Schema 선언, 독립된 다중 작업을 1회 턴으로 병렬 처리하는 Parallel Function Calling과 Call ID 기반 응답 매핑, 네트워크 재시도 및 중복 실행에 따른 부작용을 방지하기 위한 멱등성 키(Idempotency Key) 검증 및 읽기/쓰기 권한 분리**를 결합하여 완벽한 API 호출 무결성과 처리 성능을 완성

#### 한줄 요약
- **실행 부작용•재시도 가능성** 대상 따라 검증과 승인 결정
