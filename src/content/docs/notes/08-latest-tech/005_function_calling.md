## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **함수 호출(Function Calling)**: 모델이 자연어 의도를 함수명과 구조화된 인자로 변환하여 호스트에 실행을 요청하는 연계 방식을 의미한다.

</details>

- 정의/개념: 자연어 의도를 함수명•구조화 인자로 변환하는 **함수 호출 연계 방식**임.
- 배경/필요성: 자연어만으로는 함수•인자•권한•부작용 경계를 검증하기 어려움.

#### 한줄 요약
- **함수 호출**에서 모델은 함수•인자를 제안하고 호스트는 검증•실행한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **구조화 출력(Structured Output)**: 모델의 응답을 지정된 데이터 스키마에 맞춰 후속 시스템이 안정적으로 해석하게 하는 기능이다.
- **자바스크립트 객체 표기법 스키마(JavaScript Object Notation Schema, JSON Schema)**: 함수 인자의 자료형•필수 필드•허용 범위를 구조적으로 제한하는 명세이다.
- **형식 축(Format Axis)**: 함수 설명과 스키마로 함수명•인자 구조를 제한하는 기능 영역을 말한다.
- **실행 축(Execution Axis)**: 호출 식별자로 실행•재시도 결과를 연결하고 호스트가 실제 함수를 검증하는 기능 영역을 지칭한다.

</details>

- **형식 축**: 함수 설명•**JSON 스키마** 기반 함수•인자 구조를 제한함.
- 도구 선택 정책 기반 자동•필수•금지 호출 제어가 핵심임.
- **실행 축**: 호출 ID로 병렬•재시도 결과를 연결해 호스트를 검증함.

#### 한줄 요약
- **JSON 스키마**는 형식을 제한하나 값•부작용은 미보장이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **함수 스키마(Function Schema)**: 함수의 목적과 인자 이름•자료형•필수 여부•허용 범위를 선언하는 계약을 뜻한다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 호스트 실행기가 검증된 함수 요청을 실제 업무 기능과 연결하는 인터페이스이다.
- **호출 식별자(Call ID)**: 병렬•재시도 함수 요청과 각 실행 결과를 정확히 연결하는 고유 값이다.

</details>

```text
                  [함수 명세]
                       |
                  [모델 라우터]
                       |
                  [검증•정책]
                       |
                 [호스트 실행기]
```

선의 의미: 함수 명세와 모델 라우터의 제안이 검증•정책 경계를 통과해 호스트 실행기에 연결되는 함수 호출 계약 구조를 나타냄.

| 구성요소 | 책임 |
|:---|:---|
| 함수 명세 | **함수 스키마**와 **JSON 스키마**를 제공함 |
| 모델 라우터 | 함수•인자•병렬 호출을 제안함 |
| 검증•정책 | 형식•값•권한•부작용을 검사함 |
| 호스트 실행기 | **API** 함수와 **Call ID** 및 결과를 연결함 |

#### 한줄 요약
- **함수 스키마**와 호스트 검증•실행 결과를 호출 계약으로 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **함수명•설명•인자 스키마 제공(Schema Provision)**: 선택 가능한 함수와 필수 필드•자료형•허용 범위를 제시하는 단계이다.
- **함수명•인자•호출 ID 제안(Function Proposal)**: 자연어 요청을 구조화된 실행 의도로 변환하는 단계이다.
- **형식•값•권한 검증 후 실행(Verified Execution)**: 원문•업무 규칙•권한과 대조해 승인된 함수를 호출하는 단계를 말한다.
- **실행 결과•오류 반환(Execution Return)**: 함수 출력과 실패 원인을 호스트에 전달하는 단계이다.
- **호출 ID와 결과 연결(ID/Result Linking)**: 병렬 호출•재시도 결과를 올바른 요청에 결합하는 단계를 지칭한다.

</details>

```text
호스트
   │ 1. 함수명•설명•인자 스키마 제공
   ▼
모델
   │ 2. 함수명•인자•호출 ID 제안
   ▼
호스트
   │ 3. 형식•값•권한 검증 후 실행
   ▼
업무 함수
   │ 4. 실행 결과•오류 반환
   ▼
호스트
   │ 5. 호출 ID와 결과 연결
   ▼
모델
```

### 동작 원리

1. **함수명•설명•인자 스키마 제공**: 선택 가능한 함수와 필수 필드•자료형•허용 범위를 제시함.
2. **함수명•인자•호출 ID 제안**: 자연어 요청을 구조화된 실행 의도로 변환함.
3. **형식•값•권한 검증 후 실행**: 원문•업무 규칙•권한과 대조해 승인된 함수를 호출함.
4. **실행 결과•오류 반환**: 함수 출력과 실패 원인을 호스트에 전달함.
5. **호출 ID와 결과 연결**: 병렬 호출과 재시도 결과를 올바른 요청에 결합함.

#### 한줄 요약
- **형식•값•권한 검증 후 실행**하고 **호출 ID와 결과 연결**로 응답을 결합한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **병렬 함수 호출(Parallel Function Calling)**: 데이터 의존성이 없는 여러 함수 요청을 모델이 함께 제안하여 호스트가 동시에 처리하게 하는 방식을 의미한다.

</details>

| 판단 기준 | 함수 호출 | 프롬프트 기반 JSON | 제약형 구조 출력 |
|:---|:---|:---|:---|
| 적용 기준 | **함수 호출**은 외부 함수 실행 의도가 필요함 | 프롬프트 JSON은 형식 유도만이 필요함 | **구조화 출력**은 실행 없는 스키마 일치가 필요함 |
| 핵심 특징 | 함수명•인자•호출 ID를 반환함 | 프롬프트로 JSON 형식을 유도함 | 구조화 출력의 스키마와 일치함 |
| 한계 | 값•권한•실행은 별도 검증이 필요함 | 형식 위반 가능성이 존재함 | 외부 함수 실행 의미가 없음 |

> 요약: **함수 호출**은 실행 의도를, **구조화 출력**은 형식을 구조화함.

#### 한줄 요약
- 데이터 의존성이 없으면 **병렬 함수 호출**로 실행 시간을 줄인다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **도구 선택 정책(Tool Choice Policy)**: 함수 호출을 자동•필수•금지하거나 특정 함수로 제한하여 모델의 호출 범위를 통제하는 정책이다.
- **멱등성(Idempotency)**: 같은 함수 요청을 여러 번 실행해도 추가 부작용 없이 동일한 상태에 도달하는 성질을 말한다.
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 스키마는 맞지만 값은 틀린 의미상 오류 | 사용자 원문•업무 데이터•허용 범위를 대조함 | 잘못된 인자 실행을 차단함 |
| 재시도로 발생하는 주문 중복 실행 | **Call ID**와 **멱등성** 키로 기존 결과를 재사용함 | 중복 업무 부작용을 방지함 |
| 상태 변경 함수의 권한 우회 | **도구 선택 정책**과 읽기•쓰기 분리 및 승인을 적용함 | 실제 업무 권한을 보호함 |

#### 한줄 요약
- **멱등성**과 인자•원문•권한을 검증한 뒤 주문 API를 호출한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>


</details>

- 외부 실행 의도는 **함수 호출**로 구조화하고 값•권한•멱등성은 호스트가 검증함.

#### 한줄 요약
- **함수 스키마**에 맞는 인자를 호스트가 검증•승인한 뒤 실행한다.
