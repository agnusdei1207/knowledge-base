## 미리 알고가기

- **엣지 인공지능 (Edge Artificial Intelligence, Edge AI)**: 현장 근처에서 추론·제어하는 기술
- **게이트웨이 (Gateway)**: 센서 데이터 수집·정제 중계 장치
- **평균 복구 시간 (Mean Time To Repair, MTTR)**: 장애 복구 속도 측정 지표
- **무선 업데이트 (Over-The-Air, OTA)**: 모델·설정 원격 배포 방식



## Ⅰ. 개요

- **정의/개념**: 현장 장치에 추론·제어를 분산 배치
- **배경/필요성**: 현장 지연·통신량·망 단절 완화

### 쉽게 이해하기 (학습용)

- 현장 가까운 장비가 중앙 서버를 기다리지 않고 판단한다

## Ⅱ. 특징

- 현장 처리가 네트워크 왕복 지연을 줄인다
- 원시 데이터 필터링이 전송량을 줄인다
- 망 단절 시 자율 동작·지연 전송을 수행한다
- 중앙 관리가 장비 버전·드리프트를 통제한다

### 쉽게 이해하기 (학습용)

- 필요한 데이터만 보내 통신량을 줄이고 단절에도 계속 동작한다

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| Sensor | 원시 데이터 생성함 |
| Gateway | 데이터 수집·동기화함 |
| Runtime | 모델 추론 수행함 |
| Actuator | 경보·제어 수행함 |
| Control | 장비 신원·OTA 관리함 |

현장 센서
├─ 게이트웨이
├─ 추론 엔진
└─ 안전 제어

### 쉽게 이해하기 (학습용)

- 현장 판단과 중앙 관리를 분리해 망 장애에도 제어함

## Ⅳ. 원리 및 절차 흐름도

요구정의
↓
배치설계
↓
현장추론
↓
운영개선

| 절차 | 설명 |
|:---|:---|
| 요구정의 | 지연·안전 기준 정의함 |
| 배치설계 | 기능·용량 배분함 |
| 현장추론 | 추론·제어·저장함 |
| 운영개선 | 모델 성능 개선함 |

### 쉽게 이해하기 (학습용)

- 현장 장비가 언제 스스로 결정하고 언제 중앙에 묻는지를 장애 상황까지 포함해 정해야 함

## Ⅴ. 종류 및 비교

| 판단 기준 | On-Device AI | Edge AI | Cloud AI |
|:---|:---|:---|:---|
| 실행 단위 | 개별 단말 | 게이트웨이 | 중앙 서버 |
| 적용 기준 | 개인화 처리 | 저지연 제어 | 통합 분석 |
| 주요 위험 | 기기 파편화 | 관리 복잡성 | 집중 장애 |

> 요약: 현장 분산 처리로 지연과 장애를 해결함

### 쉽게 이해하기 (학습용)

- 중앙·현장 처리 분담은 지연과 관리 범위를 함께 바꾼다

## Ⅵ. 실무 사례

- 물리 접근·보안 위협 대비 Secure Boot·서명 적용함
- 모델 배포는 단계적 Canary·A/B·Rollback 진행함

> 요약: 현장별 성능 관측으로 신뢰성 보장함

### 쉽게 이해하기 (학습용)

- 현장 판단의 속도와 중앙 운영의 통제력을 함께 확보해야 Edge AI가 안정적으로 유지됨

## Ⅶ. 결론

- 현장은 지연을 줄이고 중앙은 수명주기를 통제한다

### 쉽게 이해하기 (학습용)

- 현장은 즉시 판단하고 중앙은 여러 장비의 상태를 관리한다
