## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시스템 프롬프트(System Prompt)**: 모델의 공통 역할•정책•출력 방식을 사용자 요청보다 높은 권한으로 설정하는 상위 지시다.
- **행동 계약**: 역할•허용 행동•금지 조건•출력 형식을 정의한 계약이다.

</details>

- 정의/개념: 대화 전체의 역할•정책을 설정하는 **시스템 프롬프트**
- 배경/필요성: 요청별 지시만으로는 **공통 행동 경계** 유지 불가

#### 한줄 요약
- 사용자 요청보다 우선하는 **공통 역할•행동 정책** 설정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지시 계층(Instruction Hierarchy)**: 충돌하는 지시를 메시지의 권한 순서에 따라 해석하는 우선순위 체계다.
- **신뢰 경계(Trust Boundary)**: 운영자가 작성한 지시와 외부에서 들어온 비신뢰 데이터를 구분하는 논리적 경계다.
- **신원•접근 관리(Identity and Access Management, IAM)**: 모델 밖에서 사용자와 도구의 접근 권한을 검증하고 집행하는 체계다.

</details>

- **지시 계층**: 하위 입력과 상위 지시의 충돌 조정
- **문맥 경계**: 비신뢰 데이터와 지시 분리
- **IAM**: 사용자•도구 접근 권한을 외부에서 집행
- **도구 권한**: 모델 지시와 실제 실행 허용 분리

#### 한줄 요약
- 행동 지시는 **시스템 프롬프트**, 실행 권한은 **IAM** 기반 분리

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **문맥 경계**: 신뢰 지시와 참조 데이터의 영역과 권한을 구분하여 외부 문장을 명령으로 취급하지 않게 하는 통제다.
- **도구 계약**: 모델이 요청할 수 있는 도구•인자•오류 처리 형식을 정의한 규칙이다.
- **평가셋**: 프롬프트와 모델 변경 뒤 정책 준수와 품질을 반복 검증하도록 고정한 입력•기대 결과 모음.

</details>

```text
                 [버전•평가]
                       |
 [역할•목표] ----- [정책•제약]
                       |
                  [문맥 경계]
                       |
               [도구•출력 계약]
```

선의 의미: 버전•평가는 역할•목표와 정책•제약의 행동 계약을 관리하고, 문맥 경계는 그 상위 지시와 도구•출력 계약이 다루는 비신뢰 입력•실행 범위를 분리하는 정적 지시 계층을 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 역할•목표 | 모델의 **업무 범위•대상 사용자** 정의 |
| 정책•제약 | **금지•거부•안전 기준** 명시 |
| 문맥 경계 | **신뢰 지시•비신뢰 데이터** 구분 |
| 도구•출력 계약 | 허용 도구와 **출력 스키마** 제한 |
| 버전•평가 | 프롬프트•모델•**평가셋 추적** |

#### 한줄 요약
- **역할•정책•경계•도구 계약•평가** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **권한 분리**: 모델의 지시 해석과 실제 자원 접근 허용을 나누어 외부 정책 집행기가 최종 권한을 판정하는 구조다.
- **위반 기록**: 지시 우회•유출•권한 거부 사건을 프롬프트와 모델 버전에 연결한 기록이다.

</details>

```text
운영자 ── 시스템 프롬프트 등록 ──▶ 애플리케이션
                                      │ 1. 역할•정책 구성
                                      │ 2. 신뢰 경계 적용
                                      │ 사용자 요청•문맥 전달
                                      ▼
                                    모델
                                      │ 3. 사용자 요청 해석
                                      │ 도구 호출 요청
                                      ▼
                                애플리케이션
                                      │ 권한 판정 요청
                                      ▼
                                  정책 집행기
                                      │ 4. 도구 권한 검증
                                      │ 권한 판정 결과
                                      ▼
                                애플리케이션
                                      │ 5. 응답•위반 기록
                                      └── 운영 결과 ──▶ 운영자
```

### 동작 원리

1. **역할•정책 구성**: 서비스 공통 행동 계약 확정
2. **신뢰 경계 적용**: 지시와 외부 데이터의 권한 분리
3. **사용자 요청 해석**: 지시 계층의 충돌 해소
4. **도구 권한 검증**: 모델 밖 IAM•승인 정책 집행
5. **응답•위반 기록**: 유출•우회 징후의 회귀 탐지

#### 한줄 요약
- **지시 해석•외부 권한 검증•위반 기록** 분리

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **사용자 프롬프트(User Prompt)**: 사용자가 현재 처리할 과업•질문•데이터를 요청마다 전달하는 입력.

</details>

| 프롬프트 구분 | 시스템 프롬프트 | 사용자 프롬프트 |
|:---|:---|:---|
| 적용 기준 | **서비스 공통 지시** | **요청별 가변 지시** |
| 핵심 특징 | 상위 **역할**•**정책** 설정 | 현재 **과업**•**데이터** 전달 |
| 한계 | **시스템 지시 유출•무시** 가능 | 상위 정책 변경 불가 |

#### 한줄 요약
- 공통 정책은 **시스템 프롬프트**, 현재 과업은 **사용자 프롬프트**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **프롬프트 주입(Prompt Injection)**: 외부 입력에 악성 지시를 섞어 모델의 기존 지시를 무시하거나 우회하도록 유도하는 공격이다.
- **프롬프트 유출(Prompt Leakage)**: 시스템 지시나 민감한 문맥이 모델 응답으로 노출되는 현상이다.
- **회귀 시험(Regression Test)**: 프롬프트나 모델 변경 뒤 기존 정책 위반이 다시 발생하지 않는지 반복 확인하는 시험.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프롬프트 주입 | **비신뢰 입력** 데이터 영역으로 격리 | **상위 지시 변조** 차단 |
| 프롬프트 유출 | 비밀 제거•**외부 저장소** 사용 | **원문 노출 범위** 축소 |
| 권한 검증 우회 | **IAM•도구 허용 목록** 및 승인 적용 | **위험 실행** 차단 |
| 변경 회귀 | 버전 고정•**공격 평가셋** 회귀 시험 | 정책 위반의 **조기 발견** |

#### 한줄 요약
- **비밀 분리•외부 권한•공격 회귀 시험** 적용

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 전이 차단**: 모델 행동의 정책 위반이 실행 권한과 외부 자원으로 이어지지 않게 분리하는 통제로 정의된다.

</details>

- 모델 행동에는 **지시 계층•문맥 경계**, 실행 권한에는 **IAM•도구 정책** 적용

#### 한줄 요약
- **행동 지시•실행 권한** 분리로 위험 전이 차단
