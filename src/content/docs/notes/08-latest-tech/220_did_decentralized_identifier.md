## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **분산 식별자(Decentralized Identifier, DID)**: 중앙 등록기관에 종속되지 않고 식별 주체가 검증 수단과 수명주기를 제어하는 URI 형태의 식별자이다.
- **통합 자원 식별자(Uniform Resource Identifier, URI)**: 인터넷 자원을 고유하게 식별하는 표준 문자열 형식이다.

</details>

- 정의: 중앙기관 없이 주체가 검증 수단•수명주기를 제어하는 **DID**
- 배경/필요성: 서비스마다 발급한 계정에 신원이 묶이면 그 기관이 사라지거나 정책을 바꿀 때 축적한 **신원 관계**를 잃고 처음부터 다시 쌓는 비용을 치르므로, 식별자와 검증용 공개키를 주체가 직접 소유하고 서비스는 그 식별자를 참조만 하도록 신뢰 근거를 옮길 필요

#### 한줄 요약

- 기관이 발급한 계정 대신 주체가 식별자와 검증 수단을 직접 관리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **탈중앙 제어**: 중앙 등록기관 대신 식별 주체가 키와 갱신 권한을 통해 식별자의 상태를 통제하는 방식이다.

</details>

- 중앙기관 없이 공개키로 제어권•서명을 확인하는 **탈중앙 제어•암호학적 검증**
- 기반 시스템별 생명주기 규칙을 정의하는 **DID 메서드**
- 검증 방법과 서비스 엔드포인트를 제공하는 **DID 문서**

#### 한줄 요약

- 식별자는 고정해 두고 **DID 문서의 공개키•서비스 정보**만 갱신하는 구조라, 키를 교체해도 상대가 알던 식별자는 그대로 남아 관계를 다시 맺을 필요가 없다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **분산 식별자 문서(DID Document)**: 분산 식별자를 해석하여 얻는 검증 방법•서비스 엔드포인트•제어 관계 정보이다.
- **DID 주체**: DID가 식별하는 사람•조직•장치•데이터 대상이다.
- **DID 제어자**: DID 문서의 키•서비스 정보를 갱신할 권한을 가진 주체이다.
- **DID 메서드**: 특정 장부•네트워크에서 DID를 생성•해석•갱신•비활성화하는 규칙이다.
- **검증 방법(Verification Method)**: 주체가 키를 통제한다는 서명•인증을 검증하기 위한 공개키와 절차이다.
- **DID 리졸버**: DID 문자열을 해당 메서드로 해석해 최신 DID 문서와 메타데이터를 반환하는 구성요소이다.

</details>

**DID 주체**의 키 제어와 리졸버의 문서 해석

```text
                         [DID 주체]
                              |
                        [DID 메서드]
                         /          \
                  [DID 문서] ----- [DID 리졸버]
```

선의 의미: 주체의 식별자 제어와 메서드 기반 문서 해석 관계

| 구성요소 | 책임 |
|:---|:---|
| DID 주체 | 식별자와 **인증 키 제어** |
| DID 메서드 | **생성•해석 규칙**과 갱신•비활성화 절차 |
| DID 문서 | **검증 방법•서비스 정보** 제공 |
| DID 리졸버 | 메서드 기반 **DID 문서 해석** |

#### 한줄 요약

- 주체의 키 관리와 **메서드 기반 DID 문서 해석**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **분산 식별자 해석**: 분산 식별자 메서드 규칙에 따라 식별자의 현재 문서와 상태를 조회하는 과정이다.

</details>

```text
[검증자] ── DID 해석 요청 ──▶ [DID 리졸버]
                                  │ 1. 메서드 식별
                                  ▼
                              [DID 메서드]
                                  │ 2. 최신 문서•상태 조회
                                  ▼
                              [분산 저장소]
                                  │ DID 문서•메타데이터
                                  ▼
[검증자] ◀─ DID 문서•검증 정보 ─ [DID 리졸버] ◀─ 해석 결과 ─ [DID 메서드]
```

### 동작 원리

1. 메서드 식별: DID 문자열에서 해석 규칙과 기반 시스템 선택
2. 최신 문서•상태 조회: 갱신•비활성화 상태와 검증 방법 확보

#### 한줄 요약

- DID 해석으로 **최신 공개키•상태** 확보 후 서명 검증

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **검증 가능 자격증명(Verifiable Credential, VC)**: 발급자가 자격 주장에 암호학적 증명을 결합한 디지털 자격증명이다.

</details>

| 구분 | DID | DID 문서 | VC |
|:---|:---|:---|:---|
| 핵심 대상 | 주체 **식별자** | **검증 정보** | **자격 주장** |
| 관리 주체 | **DID 제어자** | **DID 제어자** | **발급자** |
| 주요 기능 | **주체 식별** | **키•서비스 해석** | **속성•자격 증명** |
| 주요 한계 | **메서드 상호운용성** | **개인정보 노출** | **발급자 신뢰•상태 확인** |

#### 한줄 요약

- 셋은 누구인지•어떻게 검증하는지•무엇을 주장하는지를 나눠 맡으므로, DID와 DID 문서만으로는 자격을 증명하지 못하고 **VC는 자격 주장**을 얹어야 판단 근거가 완성된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **키 회전**: 기존 검증키의 노출 위험을 줄이기 위해 분산 식별자 문서의 키를 새 키로 안전하게 교체하는 절차이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **키 분실•탈취** | **다중 복구키•폐기 절차**와 키 회전 | 제어권 복구와 **피해 제한** |
| **상관관계 추적** | **관계별 DID•최소 정보** 문서 | **개인정보 노출** 감소 |
| **메서드 종속성** | **표준 리졸버•상호운용 시험** | **해석 결과 일관성** 확보 |
| VC **상태 검증 누락** | **폐기•정지 상태 목록** 연계 | **유효 자격**만 수용 |

#### 한줄 요약

- DID 문서 키와 **VC 서명•폐기 상태** 확인

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **계층 분리**: 주체 식별•키 해석과 자격 주장의 발급•검증을 별도로 관리하는 원칙이다.

</details>

- 주체 식별에는 **DID**, 자격 주장에는 **VC**를 구분 적용

#### 한줄 요약

- DID로 주체•키 확인, **발급자 서명 VC**로 자격 검증
