## 미리 알고 가기

- **분산 식별자(Decentralized Identifier, DID)**: 중앙 등록기관에 종속되지 않고 주체가 제어하는 URI 형태의 식별자
- **DID 문서(DID document)**: DID를 해석해 얻는 검증 방법·서비스 엔드포인트·제어 관계 정보
- **DID 메서드(DID method)**: `did:method:id`의 메서드별 생성·해석·갱신·비활성화 규칙
- **검증 가능 자격증명(Verifiable Credential, VC)**: 발급자가 서명한 자격 주장으로 DID와 별도 계층

## Ⅰ. 개요

- 정의/개념: 주체가 제어하고 검증 가능한 **분산 식별자**
- 배경/필요성: 중앙 계정 종속으로 서비스 간 **신원 관계 이전 곤란**

### 쉽게 이해하기 (학습용)

- 기관이 발급한 계정 대신 주체가 식별자와 검증 수단을 직접 관리한다.

## Ⅱ. 특징

- **탈중앙 제어**: 중앙 등록기관 없이 주체가 식별자 통제
- **암호학적 검증**: 공개키로 제어권과 서명 검증
- **DID 메서드**: 기반 시스템별 생명주기 규칙 정의
- **DID 문서**: 검증 방법과 서비스 엔드포인트 제공

### 쉽게 이해하기 (학습용)

- DID는 주소이고 DID 문서는 주소의 공개키와 연락 경로를 알려 주는 안내서다.

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 3
  A["DID 주체"]
  B["DID 메서드"]
  C["DID 문서"]
  D["검증자"]
  A --> B
  B --> C
  C --> D
```

| 구성요소 | 역할 |
|:---|:---|
| DID 주체 | 식별자와 **인증 키 제어** |
| DID 메서드 | **생성·해석·갱신·비활성화** 규칙 |
| DID 문서 | **검증 방법·서비스 정보** 제공 |
| DID 리졸버 | 메서드 기반 **DID 문서 해석** |

### 쉽게 이해하기 (학습용)

- 주체가 키를 관리하고 리졸버가 메서드 규칙에 따라 DID 문서를 찾는다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
  participant S as DID 주체
  participant M as DID 메서드
  participant R as DID 리졸버
  participant V as 검증자
  S->>M: 1. DID 생성
  V->>R: DID 해석 요청
  R->>M: 2. DID 문서 조회
  M-->>R: DID 문서
  R->>R: 3. 검증 방법 해석
  R-->>V: 검증 정보
  S->>M: 4. 문서 갱신·비활성화
```

**동작 원리**

- **1. DID 생성**: 메서드 규칙에 따라 식별자와 문서 등록
- **2. DID 문서 조회**: 기반 시스템에서 최신 문서 확보
- **3. 검증 방법 해석**: 공개키와 제어 관계 추출
- **4. 문서 갱신·비활성화**: 제어권으로 생명주기 변경

### 쉽게 이해하기 (학습용)

- 검증자는 DID를 리졸버에 보내 공개키를 얻고 서명 검증에 사용한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | DID | DID 문서 | VC |
|:---|:---|:---|:---|
| 핵심 대상 | 주체 **식별자** | **검증 정보** | **자격 주장** |
| 관리 주체 | **DID 제어자** | **DID 제어자** | **발급자** |
| 주요 기능 | **주체 식별** | **키·서비스 해석** | **속성·자격 증명** |
| 주요 한계 | **메서드 상호운용성** | **개인정보 노출** | **발급자 신뢰·상태 확인** |

### 쉽게 이해하기 (학습용)

- DID는 식별자, DID 문서는 검증 안내서, VC는 서명된 자격증명이다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| **키 분실·탈취** | **다중 복구키·순환·폐기 절차** | 제어권 복구와 **피해 제한** |
| **상관관계 추적** | **관계별 DID·최소 문서 정보** | **개인정보 노출** 감소 |
| **메서드 종속성** | **표준 리졸버·상호운용 시험** | **해석 결과 일관성** 확보 |
| **VC 상태 검증** | **폐기·정지 상태 목록** 연계 | **유효 자격**만 수용 |

### 쉽게 이해하기 (학습용)

- 채용 시스템은 DID 문서의 키 상태와 발급기관 VC의 서명·폐기 상태를 함께 확인한다.

## Ⅶ. 결론

- 주체 식별에는 **DID**, 자격 주장에는 **VC**를 분리 적용

### 쉽게 이해하기 (학습용)

- DID로 주체와 키를 확인하고, 실제 자격은 발급자가 서명한 VC로 검증한다.
