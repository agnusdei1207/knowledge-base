## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **샌드박스(Sandbox)**: 신뢰할 수 없는 코드와 도구를 격리된 환경에서 실행하여 호스트 자원에 미치는 영향을 제한하는 보안 경계를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **최소 권한(Least Privilege)**: 실행 주체에 작업 수행에 필요한 자원과 행동만 제한된 시간 동안 허용하는 원칙으로 정의된다.

</details>

- 정의/개념: 비신뢰 코드의 권한•자원•통신을 제한하는 **샌드박스**
- 배경/필요성: 비신뢰 코드를 호스트에서 직접 실행하면 파일 변조•정보 유출•자원 고갈 피해가 확산됨.

#### 한줄 요약
- 비신뢰 실행에 **격리 경계•최소 권한•자원 상한** 적용

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **일회성 환경(Ephemeral Environment)**: 작업마다 새로 만들고 결과 반출 뒤 폐기하여 이전 실행 상태가 남지 않게 하는 환경을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **자원 할당량(Resource Quota)**: 연산•메모리•저장공간•실행 시간에 강제하는 사용 상한이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **중앙처리장치(Central Processing Unit, CPU)**: 명령을 해석하고 연산을 수행하는 처리장치이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **일회성 환경**: 작업마다 비특권 경계 생성•폐기
- **자원 할당량**: CPU•메모리•저장•시간 상한
- **최소 권한**: 시스템 호출•통신•파일 접근 제한
- **결과 검증**: 허용 산출물 반출 후 환경 폐기

#### 한줄 요약
- **시스템 호출•통신•파일•자원•반출** 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **보안 컴퓨팅 모드(Secure Computing Mode, Seccomp)**: 프로세스의 리눅스 시스템 호출을 정책으로 필터링하는 커널 기능으로 정의된다.
- **외부 통신 통제(Egress Control)**: 샌드박스에서 나가는 통신의 목적지•프로토콜•포트를 허용 목록으로 제한하는 통제를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **비특권 프로세스(Unprivileged Process)**: 관리자 권한 없이 실행되어 침해 시 호스트에 행사할 수 있는 권한을 줄인 프로세스를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

```text
                     [의존성 관리]
                           |
                       [실행 격리]
                 /          |          \
          [데이터 경계] [네트워크 통제] [자원 관리자]
```

선의 의미: 의존성 관리는 실행 격리의 신뢰 기반을 고정하고, 실행 격리는 데이터 경계•네트워크 통제•자원 관리자를 함께 적용해 호스트와 외부 자원 사이의 피해 반경을 제한하는 정적 샌드박스 경계를 뜻함.

| 구성요소 | 책임 |
|:---|:---|
| 의존성 관리 | 최소 이미지와 패키지 버전을 고정함 |
| 실행 격리 | **Seccomp•비특권 프로세스** 기반 호스트 접근을 제한함 |
| 데이터 경계 | 읽기 전용 입력과 검증 출력을 분리함 |
| 네트워크 통제 | **외부 통신 통제•목적지 허용 목록**을 적용함 |
| 자원 관리자 | **자원 할당량•환경 폐기**를 관리함 |

#### 한줄 요약
- **실행•데이터•통신•자원 경계** 후 검증 결과만 반출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **위험 기반 격리(Risk-based Isolation)**: 코드의 신뢰도와 예상 부작용에 따라 컨테이너•가상머신 같은 격리 수준을 선택하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **결과 검증(Result Verification)**: 산출물의 형식•악성 내용•민감정보를 검사하여 허용된 결과만 격리 경계 밖으로 반출하는 절차를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **위험도별 격리•권한•할당량 구성(Isolation/Privilege/Quota Configuration)**: 코드 신뢰도와 예상 부작용에 따라 격리 수준•최소 권한•자원 상한을 정하는 절차로 정의된다.
- **코드•도구 제한 실행(Restricted Execution)**: 구성된 보안 경계 안에서 시스템 호출과 자원 사용을 제한하며 작업을 수행하는 절차로 정의된다.
- **출력•행위 기록 검증(Output/Action Log Verification)**: 실행 산출물과 행위 기록에서 악성 내용•민감정보•정책 위반을 검사하는 절차이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

```text
에이전트
   │ 코드•도구 실행 요청
   ▼
정책 엔진
   │ 1. 위험도별 격리•권한•할당량 구성
   ▼
샌드박스
   │ 2. 코드•도구 제한 실행
   ▼
결과 검증기
   │ 3. 출력•행위 기록 검증
   │ 4. 일회성 환경 폐기
   │ 허용 산출물•실행 결과 반환
   ▼
에이전트
```

### 동작 원리

1. 위험도별 격리•권한•할당량 구성: **위험 기반 격리**로 경계를 설정함.
2. 코드•도구 제한 실행: 시스템 호출•자원 상한을 강제함.
3. 출력•행위 기록 검증: 악성 결과•비밀정보•정책 위반을 검사함.
4. 일회성 환경 폐기: 허용 산출물 외 잔존 상태를 제거함.

#### 한줄 요약
- 실행 전 **위험 기반 격리**, 실행 후 결과 검증•폐기

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **컨테이너(Container)**: 호스트 커널을 공유하면서 네임스페이스와 cgroup으로 프로세스•자원을 격리하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **마이크로 가상머신(Micro Virtual Machine, MicroVM)**: 경량 게스트 커널을 별도로 실행하여 컨테이너보다 강한 커널 격리 경계를 제공하는 방식이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- **컨테이너**•**MicroVM**을 실행 밀도와 격리 강도로 구분

| 격리 방식 | 컨테이너 | MicroVM |
|:---|:---|:---|
| 적용 기준 | 낮은 위험•고빈도 실행 시 적용 | 비신뢰 코드•강한 격리 시 적용 |
| 핵심 특징 | 호스트 커널 공유로 고밀도를 달성함 | 게스트 커널 분리로 경계를 강화함 |
| 한계 | 커널 취약점의 호스트 영향이 존재함 | 시작 지연•자원 오버헤드가 발생함 |

> 요약: 고밀도 실행에는 **컨테이너**, 강한 커널 격리에는 **MicroVM**을 적용함.

#### 한줄 요약
- **위험•실행 밀도**에 따라 컨테이너•MicroVM 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **격리 탈출(Sandbox Escape)**: 샌드박스 안의 코드가 취약점을 이용해 격리 경계를 넘어 호스트 권한이나 자원에 접근하는 공격을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **피해 반경(Blast Radius)**: 침해나 오작동이 영향을 미칠 수 있는 시스템•데이터•사용자의 최대 범위로 정의된다.
- **공급망 확산(Supply Chain Spread)**: 악성 산출물이 후속 시스템이나 배포 과정에 전달되어 샌드박스 밖으로 피해가 이어지는 현상을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 커널 취약점의 **격리 탈출** | 위험도에 따라 **MicroVM•비특권 사용자**를 적용함 | 호스트까지의 **피해 반경**을 축소함 |
| 외부 통신을 통한 정보 유출 | **외부 통신 통제**로 목적지•프로토콜 허용 목록을 운영함 | 비밀정보 무단 반출을 방지함 |
| 무한 실행에 따른 자원 고갈 | **자원 할당량**으로 CPU•메모리•저장공간•시간을 제한함 | 서비스 가용성을 보호함 |
| 악성 출력의 후속 감염 | **결과 검증** 후 결과만을 반출함 | 샌드박스 밖 **공급망 확산**을 차단함 |

#### 한줄 요약
- 읽기 전용 입력•**외부 통신 통제**로 정보 유출 방지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **격리 수준 선택(Isolation Level Selection)**: 실행 코드의 신뢰도와 부작용 위험에 따라 컨테이너와 MicroVM 등 격리 단계를 구분하는 결정이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 낮은 위험•고빈도는 **컨테이너**, 비신뢰 코드는 **MicroVM**

#### 한줄 요약
- **코드 신뢰도•부작용**에 따라 격리 수준 결정
