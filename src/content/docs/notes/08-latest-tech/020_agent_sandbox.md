## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **샌드박스(Sandbox)**: 신뢰할 수 없는 코드와 도구를 격리된 환경에서 실행하여 호스트 자원에 미치는 영향을 제한하는 보안 경계을 말한다.
- **최소 권한**: 실행 주체에 작업 수행에 필요한 자원과 행동만 제한된 시간 동안 허용하는 원칙로 정의된다.

</details>

- 정의/개념: 비신뢰 코드•도구의 권한•자원•통신을 제한하는 **에이전트 샌드박스**임.
- 배경/필요성: 비신뢰 코드를 호스트에서 직접 실행하면 파일 변조•정보 유출•자원 고갈 피해가 확산된음.

#### 한줄 요약
- 비신뢰 실행의 **격리 경계•최소 권한•자원 상한**을 적용한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **일회성 환경(Ephemeral Environment)**: 작업마다 새로 만들고 결과 반출 뒤 폐기하여 이전 실행 상태가 남지 않게 하는 환경을 말한다.
- **자원 할당량(Resource Quota)**: 연산•메모리•저장공간•실행 시간에 강제하는 사용 상한이다.
- **중앙처리장치(Central Processing Unit, CPU)**: 명령을 해석하고 연산을 수행하는 처리장치이다.

</details>

- **일회성 환경**: 작업마다 비특권 경계를 생성•폐기함.
- **자원 할당량**: **CPU**•메모리•저장공간•실행 시간을 통제함.
- **최소 권한**으로 시스템 호출•네트워크•파일 접근을 통제함.
- **일회성 환경**의 결과를 검사하고 환경을 폐기함.

#### 한줄 요약
- 시스템 호출•통신•파일•자원•결과 반출을 통제한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **보안 컴퓨팅 모드(Secure Computing Mode, Seccomp)**: 프로세스의 리눅스 시스템 호출을 정책으로 필터링하는 커널 기능로 정의된다.
- **외부 통신 통제(Egress Control)**: 샌드박스에서 나가는 통신의 목적지•프로토콜•포트를 허용 목록으로 제한하는 통제을 말한다.
- **비특권 프로세스**: 관리자 권한 없이 실행되어 침해 시 호스트에 행사할 수 있는 권한을 줄인 프로세스을 말한다.

</details>

```text
                     [의존성 관리]
                           |
                       [실행 격리]
                 /          |          \
          [데이터 경계] [네트워크 통제] [자원 관리자]
```

선의 의미: 의존성 관리는 실행 격리의 신뢰 기반을 고정하고, 실행 격리는 데이터 경계•네트워크 통제•자원 관리자를 함께 적용해 호스트와 외부 자원 사이의 피해 반경을 제한하는 정적 샌드박스 경계를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 의존성 관리 | 최소 이미지와 패키지 버전 고정 |
| 실행 격리 | **Seccomp•비특권 프로세스** 기반 호스트 접근 제한 |
| 데이터 경계 | 읽기 전용 입력과 검증 출력 분리 |
| 네트워크 통제 | **외부 통신 통제•목적지 허용 목록** 적용 |
| 자원 관리자 | **자원 할당량•환경 폐기** 관리 |

#### 한줄 요약
- 실행•데이터•통신•자원 경계를 적용한 뒤 검증된 결과만 반출한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **위험 기반 격리**: 코드의 신뢰도와 예상 부작용에 따라 컨테이너•가상머신 같은 격리 수준을 선택하는 방식을 말한다.
- **결과 검증**: 산출물의 형식•악성 내용•민감정보를 검사하여 허용된 결과만 격리 경계 밖으로 반출하는 절차을 의미한다.
- **위험도별 격리•권한•할당량 구성**: 코드 신뢰도와 예상 부작용에 따라 격리 수준•최소 권한•자원 상한을 정하는 절차로 정의된다.
- **코드•도구 제한 실행**: 구성된 보안 경계 안에서 시스템 호출과 자원 사용을 제한하며 작업을 수행하는 절차로 정의된다.
- **출력•행위 기록 검증**: 실행 산출물과 행위 기록에서 악성 내용•민감정보•정책 위반을 검사하는 절차이다.

</details>

```text
에이전트
   │ 코드•도구 실행 요청
   ▼
정책 엔진
   │ 1. 위험도별 격리•권한•할당량 구성
   ▼
샌드박스
   │ 2. 코드•도구 제한 실행
   ▼
결과 검증기
   │ 3. 출력•행위 기록 검증
   │ 4. 일회성 환경 폐기
   │ 허용 산출물•실행 결과 반환
   ▼
에이전트
```

1. **위험도별 격리•권한•할당량 구성**: **위험 기반 격리**로 경계를 설정함.
2. **코드•도구 제한 실행**: 시스템 호출•자원 상한을 강제함.
3. **출력•행위 기록 검증**: 악성 결과•비밀정보•정책 위반을 검사함.
4. **일회성 환경 폐기**: 허용 산출물 외 잔존 상태를 제거함.

#### 한줄 요약
- 실행 전 위험 기반 격리, 실행 후 **결과 검증**과 환경 폐기가 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **컨테이너(Container)**: 호스트 커널을 공유하면서 네임스페이스와 cgroup으로 프로세스•자원을 격리하는 방식을 말한다.
- **마이크로 가상머신(Micro Virtual Machine, MicroVM)**: 경량 게스트 커널을 별도로 실행하여 컨테이너보다 강한 커널 격리 경계를 제공하는 방식이다.

</details>

- **컨테이너** 및 **MicroVM** 사이를 실행 밀도와 커널 격리 강도로 구분함.

| 격리 방식 | 컨테이너 | MicroVM |
|:---|:---|:---|
| 적용 기준 | 낮은 위험•고빈도 실행 | 비신뢰 코드•강한 격리 |
| 핵심 특징 | 호스트 커널 공유로 고밀도 | 게스트 커널 분리로 경계 강화 |
| 한계 | 커널 취약점의 호스트 영향 | 시작 지연•자원 오버헤드 |

> 요약: 고밀도 실행에는 **컨테이너**, 강한 커널 격리에는 **MicroVM**을 적용한다.

#### 한줄 요약
- 위험•밀도에 따라 **컨테이너•MicroVM**을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **격리 탈출**: 샌드박스 안의 코드가 취약점을 이용해 격리 경계를 넘어 호스트 권한이나 자원에 접근하는 공격을 말한다.
- **피해 반경(Blast Radius)**: 침해나 오작동이 영향을 미칠 수 있는 시스템•데이터•사용자의 최대 범위로 정의된다.
- **공급망 확산**: 악성 산출물이 후속 시스템이나 배포 과정에 전달되어 샌드박스 밖으로 피해가 이어지는 현상을 말한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 커널 취약점의 **격리 탈출** | 위험도에 따라 **MicroVM•비특권 사용자** 적용 | 호스트까지의 **피해 반경** 축소 |
| 외부 통신을 통한 정보 유출 | **외부 통신 통제**로 목적지•프로토콜 허용 목록 운영 | 비밀정보 무단 반출 방지 |
| 무한 실행에 따른 자원 고갈 | **자원 할당량**으로 CPU•메모리•저장공간•시간 제한 | 서비스 가용성 보호 |
| 악성 출력의 후속 감염 | **결과 검증** 후 결과만 반출 | 샌드박스 밖 **공급망 확산** 차단 |

#### 한줄 요약
- 읽기 전용 입력과 **외부 통신 통제**로 정보 유출을 방지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **격리 수준 선택**: 실행 코드의 신뢰도와 부작용 위험에 따라 컨테이너와 MicroVM 등 격리 단계를 구분하는 결정이다.

</details>

- **격리 수준 선택**에 따라 낮은 위험•고빈도 실행에는 **컨테이너**, 비신뢰 코드에는 **MicroVM**을 선택함.

#### 한줄 요약
- 신뢰도•부작용으로 격리 수준을 골라 **피해 반경**을 최소화한다.
