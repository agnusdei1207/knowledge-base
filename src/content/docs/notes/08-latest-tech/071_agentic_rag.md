## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전틱 검색 증강 생성(Agentic Retrieval-Augmented Generation, Agentic RAG)**: 목표 분해•도구 호출•근거 평가를 반복하는 RAG 방식이다.

</details>

- 정의: 계획•도구 호출•근거 평가를 반복하는 **Agentic RAG**
- 배경/필요성: 한 번 검색해 한 번 생성하는 RAG는 검색이 빗나가도 그대로 답을 만들어 **복합 질의 분해•검색 실패 복구**를 사용자의 재질의 비용으로 떠넘기므로, 검색과 생성 사이에 질의를 나누고 결과를 평가해 재검색을 결정하는 에이전트 제어 루프를 끼워 넣음

#### 한줄 요약
- **하위 목표 분해•도구 검증**은 검색 실패를 스스로 복구하는 대신 질의당 호출 수와 지연을 몇 배로 늘리므로, 단순 조회까지 에이전트 루프에 태우면 오히려 손해다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **반추**: 근거 충족도를 평가하고 다음 행동을 조정하는 단계이다.
- **종료 조건**: 근거 충족도와 비용 한도로 반복 탐색을 끝내는 규칙이다.

</details>

- **하위 목표•상태 실행**: 계획 기반 작업 분해
- **근거 평가•반추**: 재검색•전략 수정 판정
- **도구 라우팅•종료 조건**: 행동 권한과 반복 통제

#### 한줄 요약

- 상태 기반 행동에서 **반복•권한 오용** 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **도구 라우터(Tool Router)**: 목표와 입력 스키마에 맞는 도구를 호출하는 구성요소이다.
- **근거 평가기**: 자료의 관련성•충분성•모순 여부를 판정하는 구성요소이다.
- **정책 통제기**: 권한과 비용, 반복 횟수 및 중단 규칙을 실행 과정에 강제한다.

</details>

```text
                        [정책 통제기]
                     /         |         \
                [계획기]  [도구 라우터]  [근거 평가기]
                     \         |         /
                       [상태•메모리]
```

선의 의미: 정책 통제기는 계획기, 도구 라우터, 근거 평가기의 권한•비용•중단 경계를 제한하고, 세 구성요소는 상태•메모리를 공통 실행 근거로 사용한다.

| 구성요소 | 책임 |
|:---|:---|
| 계획기 | **목표•완료 조건**과 작업 순서 제안 |
| 상태•메모리 | **결과•출처**와 오류•남은 목표 저장 |
| 도구 라우터 | **권한**•**스키마** 기반 도구 호출 |
| 근거 평가기 | **관련성•충분성**과 모순 검사 |
| 정책 통제기 | **비용•권한**과 단계•중단 규칙 강제 |


#### 한줄 요약
- **계획•상태**와 도구•근거 평가•정책 통제 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **하위 목표**: 복합 질의를 검증 가능한 단위 작업으로 분해한 목표.
- **상태 메모리**: 도구 실행 결과와 오류, 출처 및 남은 목표를 다음 판단에 전달하는 기록.

</details>

```text
계획기
   │ 1. 하위 목표•완료 조건 저장
   ▼
┌──────── 근거 충족•행동 예산 소진 전 ────────┐
│ 상태•메모리 ── 2. 목표별 도구 선택 ──▶ 도구 라우터
│ 상태•메모리 ◀─ 3. 실행 결과•오류 기록 ──┘
│        │ 4. 근거 관련성•충분성 평가
│        ▼
│   근거 평가기 ── 5. 재탐색•종료 판정 ──▶ 계획기
└──────────────────────────────────────────────┘
```

### 동작 원리

1. 하위 목표•완료 조건 저장: **검증 가능 단위**로 복합 질의 분해
2. 목표별 도구 선택: 스키마•권한에 맞는 **도구 라우팅**
3. 실행 결과•오류 기록: **상태 메모리•남은 목표** 갱신
4. 근거 관련성•충분성 평가: 출처 일치와 **증거 공백** 판정
5. 재탐색•종료 판정: 근거 충족•예산에 따른 **반복 제어**

#### 한줄 요약
- **근거 충족•행동 예산**에 따라 재탐색 종료

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고정 검색 증강 생성(Fixed Retrieval-Augmented Generation, 고정 RAG)**: 미리 정한 단일 검색•생성 절차를 한 번 수행하는 방식.
- **워크플로 검색 증강 생성(Workflow Retrieval-Augmented Generation, 워크플로 RAG)**: 사전 조건과 분기에 따라 여러 검색 단계를 수행하는 방식이다.
- **에이전틱 검색 증강 생성(Agentic Retrieval-Augmented Generation, 에이전틱 RAG)**: 상태와 근거 평가로 다음 검색 행동을 결정하는 방식이다.

</details>

RAG 실행 방식은 고정형•워크플로형•에이전틱형으로 구분한다.

| RAG 방식 | 고정 RAG | 워크플로 RAG | Agentic RAG |
|:---|:---|:---|:---|
| 적용 기준 | 질문•데이터가 **일정한 상황** | 절차•예외 분기가 **명확한 업무** | 복합 목표의 **반복 탐색** |
| 핵심 특징 | **검색**•**생성** 1회 수행 | 사전 정의된 **분기 실행** | 상태•평가 기반 **행동 결정** |
| 한계 | 검색 실패의 **복구 곤란** | 미정의 상황의 **분기 누락** | 반복 루프•**도구 비용 증가** |

#### 한줄 요약
- **질의 변동성•분기 명확성**에 따라 RAG 방식 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **무한 탐색 루프**: 근거 부족 판정이 반복되어 검색과 도구 호출이 끝나지 않는 문제.
- **도구 오선택**: 목표나 입력 스키마와 맞지 않는 도구를 호출해 오류와 비용을 늘리는 문제로 정의된다.
- **근거 모순**: 서로 다른 출처가 양립하기 어려운 내용을 제시하는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근거 부족으로 **반복 탐색** | **최대 단계•비용•완료 조건** 설정 | **무한 탐색 루프** 차단 |
| 부적합한 **도구 오선택** | 목표•스키마 기반 **도구 라우팅** | 호출 **실패•오용 감소** |
| 근거 간 **모순 발생** | 출처•시점 기반 **근거 평가** | **상충 근거** 식별 |

#### 한줄 요약
- **반복•누적 비용**과 중요 호출 승인 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **근거 임계값**: 답변을 확정하기 위해 근거가 충족해야 하는 최소 품질 기준이다.
- **행동 예산**: 에이전트가 한 요청에서 사용할 수 있는 도구 호출 횟수와 비용의 상한.

</details>

- 고정•명확 분기는 **고정•워크플로 RAG**, 동적 탐색은 **Agentic RAG** 선택

#### 한줄 요약
- **질의 변동성•행동 예산**과 분기 명확성에 따라 RAG 방식 결정
