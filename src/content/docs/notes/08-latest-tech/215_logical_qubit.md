## 미리 알고가기

- **논리 큐비트**: 물리 큐비트와 오류 정정 코드로 안정성을 확보한 가상 단위
- **실용성**: 물리 큐비트 개수보다 논리 큐비트의 오류 정정 품질이 중요함
- **논리 오류율**: 물리 오류율과 코드 거리 및 운영 품질에 따라 결정됨



## Ⅰ. 개요

- **정의/개념**: 오류 정정 코드에 인코딩된 양자 정보 단위
- **배경/필요성**: 물리 오류를 억제해 안정된 양자 계산을 수행

### 쉽게 이해하기 (학습용)

- 여러 큐비트가 만드는 특별한 상태 공간으로 정보를 보호하는 단위임

## Ⅱ. 특징

- 코드 공간이 정보를 다수 물리 큐비트에 분산한다.
- 간접 측정이 논리 정보 노출 없이 오류를 찾는다.
- 논리 게이트가 보호 상태에서 연산을 수행한다.
- 임계값·코드 거리가 논리 오류율을 결정한다.

### 쉽게 이해하기 (학습용)

- 정보를 직접 묻지 않고 오류만 감시하여 상태를 보호함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 물리 큐비트 | 인코딩에 사용되는 데이터와 측정용 큐비트 |
| 코드 공간 | 오류 정정 코드를 통해 보호되는 논리 상태 |
| 신드롬 추출 | 정보 누설 없이 오류 증상만 반복 확인 |
| 해독 엔진 | 증상 기반 오류 추정 및 프레임 갱신 |
| 연산 레이어 | 보호 상태 유지 및 논리 연산 수행 |

> 요약: 논리 상태 인코딩, 주기적 검사 및 해독으로 구성됨.

### 쉽게 이해하기 (학습용)

- 정보를 보호 상자에 넣고 지속 감시하며 오류를 보정함

## Ⅳ. 원리 및 절차 흐름도


```text
목표설정
  ↓
상태인코딩
  ↓
주기검사
  ↓
오류해독
  ↓
연산검증
```

| 절차 | 설명 |
|:---|:---|
| 목표설정 | 논리적 오류율 목표를 설정함 |
| 상태인코딩 | 물리 큐비트에 논리 정보를 인코딩함 |
| 주기검사 | 오류 증상을 매 주기 측정함 |
| 오류해독 | 오류 추정 후 보정값 반영함 |
| 연산검증 | 전체 연산 과정의 오류율 확인함 |

> 요약: 인코딩 후 지속적인 검사와 해독으로 연산을 보호함.

### 쉽게 이해하기 (학습용)

- 보호 상자를 만들고 계산 내내 검사와 해독을 반복함

## Ⅴ. 종류 및 비교

| 판단 기준 | 물리 큐비트 | 검출 가능한 큐비트 | 논리 큐비트 |
|:---|:---|:---|:---|
| 핵심 특징 | 직접 노출 | 일부 오류 감지 후 처리 | 지속적인 정정 및 보호 |
| 적용 기준 | 사전 억제 위주 | 오류 감지 시 연산 취소 | 실시간 정정 및 연산 지속 |
| 주요 위험 | 하드웨어 노이즈 | 성공 확률 및 폐기율 | 논리 오류율 및 확장성 |

> 요약: 논리 큐비트는 실시간 정정을 통한 지속적 보호를 제공함.

### 쉽게 이해하기 (학습용)

- 단순히 오류를 감지하는 단계를 넘어 지속적인 정정 보호가 필요함

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- logical memory benchmark: 양자 hardware 팀이 distance가 다른 encoded patch에 동일한 횟수의 QEC cycle을 적용하고 logical memory error per cycle을 matched physical idle baseline과 비교해, 보호 비용이 실제 정보 보존 이득으로 이어지는지 판단함
- fault-tolerant logical CNOT 제공: runtime 팀이 lattice surgery의 merge·split 중 syndrome을 반복 추출하고 decoder·feedforward를 연결해 correlated fault propagation과 logical CNOT error를 측정한 뒤 compiler에 검증된 logical gate primitive로 노출함

## Ⅶ. 결론

- 논리 오류율·게이트 비용으로 논리 큐비트 규모 결정

### 쉽게 이해하기 (학습용)

- 여러 큐비트의 이름보다 실질적인 오류 감소와 연산 가능성이 중요함
