## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **논리 큐비트(Logical Qubit)**: 양자 정보를 오류 정정 코드 공간에 인코딩해 물리 오류로부터 보호하는 정보 단위다.

</details>

- 정의: 오류 정정 **코드 공간**에 인코딩된 보호 양자 정보 단위
- 배경/필요성: 물리 큐비트 하나는 연산마다 오류를 누적해 회로가 길어질수록 **계산 신뢰성 상실**에 이르므로, 여러 물리 큐비트가 이루는 코드 공간에 정보를 분산하고 정정을 반복하는 상위 단위를 두어 오류율을 회로 길이에서 떼어 낼 필요

#### 한줄 요약

- 논리 큐비트는 정보를 여러 물리 큐비트의 **코드 공간**에 흩어 두어 국소 오류가 정보를 지우지 못하게 만든 단위이며, 그 보호를 물리 큐비트 수의 급증으로 지불한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **코드 공간**: 오류 정정 코드가 유효한 논리 상태를 표현하도록 여러 물리 큐비트 안에 정한 부분공간을 의미한다.

</details>

- 논리 정보를 다수 물리 큐비트에 분산하는 **코드 공간**
- 신드롬 측정•해독을 통한 **반복 오류 정정**
- 오류 확산을 제한하는 논리 게이트의 **보호 연산**
#### 한줄 요약

- 논리 정보 대신 **오류 신드롬**을 반복 감시

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **물리 큐비트**: 실제 장치에서 양자 상태•게이트•측정을 구현하며 논리 큐비트를 구성하는 하드웨어 정보 단위로 정의된다.
- **신드롬 추출**: 논리 상태를 붕괴시키지 않고 물리 오류의 징후를 반복 측정하는 과정을 의미한다.
- **해독 엔진**: 신드롬 이력에서 오류를 추정해 보정과 논리 상태 추적을 수행하는 고전 연산부다.
- **논리 게이트**: 오류 정정 보호를 유지하면서 코드 공간의 논리 상태를 변환하는 연산을 의미한다.

</details>

```text
                    [코드 공간] ----- [연산 레이어]
                      /      \              |
             [물리 큐비트] [신드롬 추출] ----- [해독 엔진]
```

| 구성요소 | 책임 |
|:---|:---|
| 물리 큐비트 | 인코딩용 **데이터•검사 큐비트** |
| 코드 공간 | 오류 정정 코드의 **보호 논리 상태** |
| 신드롬 추출 | 정보 누설 없는 **오류 징후 측정** |
| 해독 엔진 | 신드롬 기반 **오류 추정•프레임 갱신** |
| 연산 레이어 | 보호 상태의 **논리 연산** 수행 |

#### 한줄 요약

- **코드 공간** 인코딩과 **신드롬** 기반 오류 보정

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **반복 오류 정정**: 신드롬을 주기적으로 측정•해독해 누적 물리 오류를 추적하는 과정이다.

</details>


```text
[요구사항] ── 오류 목표 ──▶ [인코더]
   │ 1. 논리 상태 인코딩
   ▼
[신드롬 회로]
   │ 2. 신드롬 주기 검사
   ▼
[해독기]
   │ 3. 보정 프레임 갱신
   ▼
[논리 연산] ── 4. 보호된 논리 연산 ──▶ [신드롬 회로]
   └──────────── 논리 연산 검증 결과 ───▶ [요구사항]
```

### 동작 원리

1. 논리 상태 인코딩: 데이터•검사 큐비트의 **코드 공간**에 정보 매핑
2. 신드롬 주기 검사: 논리 정보 노출 없는 **오류 징후** 반복 측정
3. 보정 프레임 갱신: 측정 이력 기반 **오류 추정**과 논리 상태 추적
4. 보호된 논리 연산: 오류 확산을 제한하는 **코드 공간** 상태 변환

#### 한줄 요약

- 인코딩 후 **신드롬 측정•해독**을 반복하는 보호 연산

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **물리 대 논리 자원비**: 하나의 신뢰할 수 있는 논리 큐비트를 구현하는 데 필요한 물리 큐비트와 연산의 규모로 정의된다.

</details>

| 구분 | 물리 큐비트 | 검출 가능한 큐비트 | 논리 큐비트 |
|:---|:---|:---|:---|
| 적용 기준 | **사전 오류 억제** | 오류 감지 시 **연산 취소** | **실시간 정정•연산 지속** |
| 핵심 특징 | 장치의 **단일 큐비트** | 오류 검출 후 **결과 선별** | 코드 공간의 **오류 정정** |
| 한계 | **하드웨어 노이즈** 직접 영향 | 높은 **결과 폐기율** | 큰 **물리 자원•게이트 비용** |

#### 한줄 요약

- 논리 큐비트가 물리 큐비트와 갈리는 지점은 개수가 아니라 **반복 오류 정정**의 유무이므로, 하드웨어 규모는 물리 큐비트 수가 아니라 유지 가능한 논리 큐비트 수로 읽어야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오류 확산**: 하나의 물리 오류가 게이트 상호작용을 통해 여러 큐비트로 전파되어 논리 오류가 되는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 거리 확장에도 **논리 오류 억제 미달** | 거리별 물리•논리 오류율 비교 | 자원 대비 **논리 오류 감소** 확인 |
| 데이터•검사 큐비트의 **자원 오버헤드** | 큐비트•주기•공간시간 비용 공동 산정 | **공간시간 비용** 예측 |
| 보정 정보의 **해독•제어 지연** | 해독 처리량 시험과 제어 경로 병렬화 | 논리 연산 **일정 준수** |

#### 한줄 요약

- **논리 오류•자원비**를 함께 검증하는 운영 대책

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **논리 오류율**: 오류 정정 후 논리 상태나 연산이 잘못될 확률이다.

</details>

- 목표 **논리 오류율•해독 처리량**에 맞는 코드 규모 선택

#### 한줄 요약

- 물리 큐비트 수보다 **논리 오류 감소•연산 가능성** 우선
