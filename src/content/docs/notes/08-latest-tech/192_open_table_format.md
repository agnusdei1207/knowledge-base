## 미리 알고가기

- **오픈 테이블 포맷 (Open Table Format) 테이블 메타데이터 규격**: 스토리지 파일 집합을 테이블처럼 관리함
- **대표 구현**: Delta Lake, Apache Iceberg, Apache Hudi가 대표적임
- **핵심 개념**: 파일 포맷이 아닌 스냅샷, 트랜잭션, 스키마 관리 테이블 계층임



## Ⅰ. 개요

오픈 테이블 포맷(Open Table Format)은 객체 저장소의 데이터 파일 위에 테이블 메타데이터·스키마·파티션·스냅샷·원자 커밋과 동시성 규칙을 공개하여 독립된 엔진이 같은 논리 테이블 상태를 해석하게 하는 상위 기술 범주임

- **정의/개념**: 레이크 테이블의 메타데이터·커밋 공개 규격
- **배경/필요성**: 저장소와 다중 계산 엔진의 종속성을 분리

### 쉽게 이해하기 (학습용)

- 파일 포맷이 작성법이라면 오픈 테이블 포맷은 현재 판본과 확정 절차를 정한 공개 규칙임

## Ⅱ. 특징

- 메타데이터 계약이 파일·스키마를 식별한다.
- 스냅샷이 갱신 중 일관된 읽기를 보장한다.
- 원자 게시·충돌 검증이 동시성을 통제한다.
- 기능 구현 범위가 엔진 상호운용성을 좌우한다.

### 쉽게 이해하기 (학습용)

- 책 규칙이 공개되어도 모든 편집기가 최신 기능을 지원하는 것은 아니므로 기능별 호환을 확인해야 함

## Ⅲ. 아키텍처 및 구성요소

```text
[Query / Stream / ML Engines]
            │ format-specific client
            ▼
[Catalog + Atomic Commit Contract]
            ▼
[Snapshots / Schema / Partition / File Metadata]
            ▼
[Data Files + Delete/Change Files on Object Storage]
```

| 설계 요소 | 설명 |
|:---|:---|
| 데이터·삭제 파일 | 행과 변경 정보를 개방형 파일에 저장 |
| 테이블 메타데이터 | 스키마, 파티션, 통계 등 사양별 기록 |
| 스냅샷·버전 | 파일 집합과 버전을 연결해 일관된 조회 |
| 커밋·카탈로그 | 새 상태 원자 게시 및 이름/위치 연결 |
| 엔진 어댑터 | 사양 구현 및 계획, 읽기, 쓰기 수행 |

> 요약: 메타데이터·스냅샷·원자 커밋으로 테이블 관리

### 쉽게 이해하기 (학습용)

- 도구마다 책 규칙의 목차와 판본, 확정 절차를 이해해야 같은 내용을 보게 됨

## Ⅳ. 원리 및 절차 흐름도

```text
현재 읽기
    ↓
파일 준비
    ↓
충돌 확인?
    ↓
재시도 또는 커밋
    ↓
스냅샷 공개
```

| 절차 | 설명 |
|:---|:---|
| 계약 협상 | 엔진별 읽기/쓰기 가능 범위를 결정함 |
| 기준 상태 | 커밋 로그 등에서 기준 스냅샷을 읽음 |
| 파일 준비 | 새 데이터 파일과 메타데이터를 작성함 |
| 충돌 검증 | 변경 내용이 기준과 충돌하는지 판단함 |
| 원자 커밋 | 포맷별 게시점에 새 상태를 등록함 |
| 조회 | 선택한 스냅샷을 기반으로 질의함 |

> 요약: 파일·메타데이터 준비 후 스냅샷 확정

### 쉽게 이해하기 (학습용)

- 새 판본의 모든 장을 만든 뒤 편집 내용을 확인하고 공식 번호를 붙여 완성된 판본만 공개함

## Ⅴ. 종류 및 비교

| 판단 기준 | Delta | Iceberg | Hudi |
|:---|:---|:---|:---|
| 핵심 특징 | 트랜잭션 로그/체크포인트 | 메타데이터 트리의 원자 교체 | 타임라인 기반 상태 기록 |
| 적용 기준 | 로그 기반 배치/스트림 변경 | 숨은 파티셔닝/대규모 계획 | 증분 질의/업서트/파일 관리 |
| 주요 위험 | 버전/테이블 기능 지원 | 포맷/삭제/분기 기능 지원 | 테이블 유형/인덱스 지원 |

> 요약: 포맷별 계약을 지원하는 엔진 구현 필요

### 쉽게 이해하기 (학습용)

- 세 규칙은 책을 관리하는 방식이 달라 한 규칙용 편집기가 다른 규칙의 책을 직접 수정 못 함

## Ⅵ. 실무 사례

1. **다중 엔진 분석 테이블 포맷 선정**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

2. **저장소 정리와 과거 재현 통제**

- **상황**: 운영 병목·위험과 영향 범위를 식별함
- **적용**: 주제별 통제·절차를 대상 환경에 적용함
- **검증**: 성능·품질·위험 지표로 효과를 확인함

### 쉽게 이해하기 (학습용)

- 다중 엔진 분석 테이블 포맷 선정
- 저장소 정리와 과거 재현 통제

## Ⅶ. 결론

### 쉽게 이해하기 (학습용)
