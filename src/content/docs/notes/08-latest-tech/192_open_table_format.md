## 미리 알고가기

- **오픈 테이블 포맷(Open Table Format)**: '오픈 테이블 포맷'으로 읽으며, 객체 저장소의 파일을 논리 테이블로 관리하는 공개 메타데이터 규격
- **스냅샷(Snapshot)**: 특정 시점의 유효한 데이터 파일 집합과 테이블 상태
- **원자성·일관성·격리성·지속성(Atomicity, Consistency, Isolation, Durability, ACID)**: '에이시드'로 읽으며, 트랜잭션이 안전하게 완료되기 위한 성질
- **표기 이유**: '오픈'은 데이터 파일 형식이 아니라 **테이블 메타데이터·커밋 규칙을 여러 엔진에 공개**한다는 의미
- **대표 형식**: Delta Lake, Apache Iceberg, Apache Hudi

## Ⅰ. 개요

- 정의/개념: 객체 저장소의 데이터 파일 위에 **스키마·파티션·스냅샷·원자 커밋 규칙을 제공하는 테이블 계층**
- **배경/필요성**: 단순 파일 저장의 **동시 쓰기 충돌·일관된 버전 조회·스키마 변경 관리 한계**를 해소하기 위해 필요

### 쉽게 이해하기 (학습용)

- 데이터 파일 자체가 책의 쪽이라면, 오픈 테이블 포맷은 유효한 쪽과 현재 판본을 정하는 공개 목차·개정 규칙이다.

## Ⅱ. 특징

- 메타데이터가 **스키마·파티션·파일 통계와 유효 파일 집합**을 관리한다.
- 스냅샷과 원자 커밋으로 **일관된 읽기와 동시 쓰기 충돌 검증**을 제공한다.
- 공개 규격으로 다중 엔진 접근을 지원하지만 **형식·버전·기능별 호환성 확인이 필요**하다.

### 쉽게 이해하기 (학습용)

- 완성된 판본만 공개해 읽는 도중 내용이 섞이지 않게 하며, 도구마다 지원하는 개정 기능은 따로 확인해야 한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[질의·처리 엔진] → [카탈로그·커밋 조정]
                           ↓
                 [스냅샷·테이블 메타데이터]
                           ↓
                   [데이터·삭제 파일]
```

| 설계 요소 | 설명 |
|:---|:---|
| 데이터·삭제 파일 | **행 데이터와 변경 정보 저장** |
| 테이블 메타데이터 | **스키마·파티션·통계 관리** |
| 스냅샷 | **유효 파일 집합과 버전 연결** |
| 카탈로그·커밋 | **테이블 식별·새 상태 원자 게시** |
| 엔진 커넥터 | **형식별 읽기·쓰기·계획 수행** |

> 요약: 스냅샷 메타데이터와 원자 커밋이 파일 집합을 일관된 테이블로 만든다.

### 쉽게 이해하기 (학습용)

- 처리 엔진은 카탈로그가 가리키는 확정 스냅샷을 읽어 같은 테이블 상태를 본다.

## Ⅳ. 원리 및 절차 흐름도

```text
기준 스냅샷 읽기 → 파일·메타데이터 작성 → 충돌 검증 → 원자 커밋 → 새 스냅샷 조회
```

| 절차 | 설명 |
|:---|:---|
| 기준 스냅샷 읽기 | 현재 테이블 상태와 버전 확인 |
| 파일·메타데이터 작성 | 새 파일과 변경 메타데이터 준비 |
| 충돌 검증 | 기준 이후 변경과 쓰기 충돌 확인 |
| 원자 커밋 | 새 테이블 상태를 한 번에 게시 |
| 새 스냅샷 조회 | 확정된 파일 집합으로 질의 |

> 요약: 새 파일을 먼저 준비하고 충돌 없는 메타데이터 상태만 원자적으로 공개한다.

### 쉽게 이해하기 (학습용)

- 새 판본을 완성한 뒤 다른 편집과 충돌하지 않는지 확인하고 공식 판본 번호를 붙인다.

## Ⅴ. 종류 및 비교

| 오픈 테이블 포맷 | Delta Lake | Apache Iceberg | Apache Hudi |
|:---|:---|:---|:---|
| 적용 기준 | 배치·스트림 통합 처리 | 다중 엔진·대규모 분석 | 업서트·증분 처리 중심 |
| 핵심 특징 | 트랜잭션 로그·체크포인트 | 스냅샷·매니페스트 트리 | 타임라인·파일 그룹 |
| 한계 | 기능별 엔진 호환 확인 | 카탈로그·기능 지원 확인 | 테이블 유형 운영 복잡 |

> 요약: 변경 처리 방식과 사용하는 엔진의 읽기·쓰기 기능 지원을 기준으로 선택한다.

### 쉽게 이해하기 (학습용)

- 모두 공개 테이블 규칙이지만 판본 관리와 변경 처리 구조가 달라 엔진 호환성을 검증해야 한다.

## Ⅵ. 실무 사례

1. Spark와 Trino가 동일한 카탈로그의 분석 테이블을 공유하고 오류 배치 전 스냅샷으로 결과를 재현한다.

### 쉽게 이해하기 (학습용)

- 여러 엔진의 읽기·쓰기 기능을 시험하면 같은 스냅샷을 일관되게 공유할 수 있는지 확인할 수 있다.

## Ⅶ. 결론

- 다중 엔진에서 테이블 변경을 일관되게 처리하기 위해 커밋 원자성·기능 호환성·카탈로그 운영을 검토하여 오픈 테이블 포맷을 선택해야 한다.

### 쉽게 이해하기 (학습용)

- 오픈 테이블 포맷은 공개 규격 여부보다 실제 엔진의 읽기·쓰기 호환성이 중요하다.
