## 미리 알고가기

- **Istio**: 쿠버네티스 환경의 대표 서비스 메시 구현체임
- **데이터 플레인**: Envoy 기반 데이터 플레인과 관측·제어 기능이 핵심임
- **메시 개념**: 메시 개념과 Istio 제품 특성을 분리해 설계함



## Ⅰ. 개요

- **정의/개념**: Istiod 기반 오픈소스 서비스 메시
- **배경/필요성**: 공통 통신 정책과 앱 배포의 분리

### 쉽게 이해하기 (학습용)

- Istio는 메시의 관제소와 통신 프록시를 제공하는 구현체다.

## Ⅱ. 특징

- Istiod가 서비스 발견·정책·인증서를 관리한다
- sidecar·ambient가 데이터 평면 배치를 달리한다
- 선언 자원이 라우팅·복원력 규칙을 표현한다
- 워크로드 신원으로 mTLS·인가를 적용한다
- 두 데이터 평면 공존이 점진 전환을 돕는다

### 쉽게 이해하기 (학습용)

- 워크로드별 프록시와 노드 공유 터널 중 필요한 방식을 고를 수 있다.

## Ⅲ. 아키텍처 및 구성요소

```text
[Istiod]
    ↓
[Envoy] 또는 [ztunnel → waypoint]
```

| 설계 요소 | 설명 |
|:---|:---|
| Istiod | 검색·구성 변환·인증서 발급 |
| Sidecar Envoy | 계층 4·7 통신 정책 집행 |
| Ambient ztunnel | 계층 4 보안 터널 제공 |
| Ambient waypoint | 계층 7 라우팅·인가 집행 |
| 구성 API | 라우팅·보안 정책 선언 |

> 요약: Istiod가 구성하고 각 데이터 평면이 정책을 집행한다

### 쉽게 이해하기 (학습용)

- Istiod가 길 안내와 인증서를 배포하고 각 프록시가 현장에서 검사한다.

## Ⅳ. 원리 및 절차 흐름도

```text
서비스발견
    ↓
정책선언
    ↓
구성배포
    ↓
요청집행
```

| 절차 | 설명 |
|:---|:---|
| 대상 편입 | Sidecar 주입·ambient 등록 |
| 서비스 발견 | 서비스·신원·망 정보 수집 |
| 정책 선언 | 라우팅·보안 범위 정의 |
| 구성 배포 | xDS 구성·인증서 전달 |
| 요청 집행 | 모드별 계층 4·7 정책 적용 |
| 관측·조정 | 지표로 확대·수정·복구 |

> 요약: 대상을 편입하고 모드별 집행 경로를 검증한다

### 쉽게 이해하기 (학습용)

- 같은 정책도 모드마다 검사 위치가 달라 실제 요청 경로를 확인해야 한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | Sidecar 모드 | Ambient ztunnel | Ambient ztunnel+waypoint |
|:---|:---|:---|:---|
| 프록시 배치 | 워크로드별 Envoy | 노드별 ztunnel | ztunnel·범위별 waypoint |
| 제공 계층 | 계층 4·7 | 계층 4 보안 | 계층 4·선택 계층 7 |
| 적용 기준 | 정밀 기능·격리 | 낮은 자원 보안 기반 | 선택 범위 HTTP 정책 |

> 요약: 격리·자원·계층 7 범위로 데이터 평면을 고른다

### 쉽게 이해하기 (학습용)

- Sidecar는 개별 검사, ambient는 공용 기본 검사와 선택 정밀 검사다.

## Ⅵ. 실무 사례

1. Sidecar 지표로 카나리 비율을 조정한다
2. ztunnel 뒤 필요한 서비스만 waypoint를 둔다

### 쉽게 이해하기 (학습용)

- 버전별 오류와 지연을 보고 신규 경로를 확대하거나 되돌린다.
- 기본 암호화는 넓게 적용하고 HTTP 정책은 필요한 곳에만 둔다.

## Ⅶ. 결론

- 요청 경로·정책 계층·자원 기준으로 Istio 모드를 고른다.
