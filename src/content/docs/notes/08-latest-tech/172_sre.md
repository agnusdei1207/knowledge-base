## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **사이트 신뢰성 공학(Site Reliability Engineering, SRE)**: 소프트웨어 공학으로 서비스 신뢰성을 정량화하고 운영하는 공학 체계이다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 일정 기간에 달성하기로 정한 사용자 중심 품질 지표의 목표을 의미한다.

</details>

- 정의: SLO•오류 예산•자동화로 신뢰성을 운영하는 **SRE**이다.
- 배경/필요성: 서비스 확장으로 **토일•변경 판단 충돌** 증가

#### 한줄 요약

- 사용자에게 필요한 안전 수준을 수치로 정하고, 반복 대응은 자동화하며, 남은 실패 여유로 배포 여부를 결정하는 방식이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **오류 예산(Error Budget)**: SLO가 허용한 실패량으로 변경과 안정화의 우선순위 판단 기준이다.
- **토일(Toil)**: 반복적•수동적이며 자동화할 수 있고 서비스 성장에 비례해 늘어나는 운영 업무이다.
- **서비스 수준 지표(Service Level Indicator, SLI)**: 사용자가 경험한 서비스 품질을 측정한 값로 정의된다.

</details>

- 사용자 중심 SLI•SLO•오류 예산 기반 **신뢰성 목표•변경 기준 정량화** 핵심임.
- 토일 감축•자동화•온콜 기반 **확장 가능한 운영 체계** 핵심임.
- 비난 없는 사후 분석 기반 **장애 원인의 설계•자동화 환류** 핵심임.
#### 한줄 요약

- 허용 실패량을 기준으로 배포와 안정화를 결정하고, 반복 사고와 수작업을 시스템 개선으로 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사용자 여정**: 서비스에서 사용자가 달성하려는 핵심 행위와 결과의 흐름을 의미한다.
- **SLI 측정**: 사용자 여정의 성공•지연•품질을 정량화하는 개념을 말한다.
- **SLO 설정**: 평가 기간과 달성할 SLI 목표 수준을 합의하는 설정을 말한다.
- **오류 예산 운영**: 허용 실패량을 변경과 안정화 우선순위에 연결하는 개념이다.
- **온콜(On-call)**: 장애 경보를 받고 정한 시간 안에 대응하는 담당 체계을 말한다.
- **관측성(Observability)**: 로그•지표•추적을 통해 서비스 내부 상태와 사용자 영향을 추론하는 능력을 말한다.
- **자동화**: 반복 운영 절차를 소프트웨어로 실행하여 토일과 오류를 줄이는 개념로 정의된다.
- **사후 분석**: 장애 원인•교훈•재발 방지 조치를 운영 설계에 환류하는 활동로 정의된다.

</details>

```text
                        [사용자 여정]
                              |
                            [SLI]
                              |
                            [SLO]
                              |
                         [오류 예산]
                      /       |       \
                 [관측성]    [온콜]    [자동화]
                      \       |       /
                         [사후 분석]
```
선의 의미: 사용자 여정은 SLI•SLO•오류 예산의 상위 품질 경계이고, 오류 예산은 관측성•온콜•자동화의 운영 우선순위를 통제하며 사후 분석은 세 영역의 장애 교훈을 시스템 개선에 함께 환류한다.

| 구성요소 | 책임 |
|:---|:---|
| 사용자 여정 | **핵심 사용자 행위와 영향 정의** |
| SLI | **사용자 품질 측정값 산출** |
| SLO | **평가 기간•목표 수준 설정** |
| 오류 예산 | **허용 실패량과 변경 기준 제공** |
| 관측성 | **증상•원인•사용자 영향 추론** |
| 온콜 | **경보 수신•장애 대응 책임 운영** |
| 자동화 | **반복 운영 절차•토일 감축** |
| 사후 분석 | **장애 교훈•재발 방지 환류** |

#### 한줄 요약

- 고객이 중요하게 느끼는 품질을 재고, 사고 대응과 반복 업무 개선까지 하나의 운영 순환으로 묶는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **소진율(Burn Rate)**: 허용 속도 대비 오류 예산이 실제로 소진되는 속도의 비율을 의미한다.
- **비난 없는 사후 분석(Blameless Postmortem)**: 개인 비난보다 시스템 원인•교훈•재발 방지 조치에 집중하는 사고 분석하는 활동을 의미한다.

</details>

SLI와 SLO의 소진 상태를 운영 조치에 연결한다.

```text
사용자 여정•신뢰성 담당
   │ 1. 사용자 성공 기준 정의
   │ 2. SLO•오류 예산 전달
   ▼
관측 시스템
   │ 3. 예산 소진 상태 전달
   ▼
개발•운영팀
   │ 4. 대응•개선 과제 전달
   ▼
자동화•사후 분석
   └── 5. 자동화•학습 결과 ──▶ 사용자 여정•신뢰성 담당
```

### 동작 원리

1. 사용자 성공 기준 정의: 사용자 여정과 성공•지연 SLI 선정
2. SLO•오류 예산 전달: 평가 기간•목표•허용 실패량 합의
3. 예산 소진 상태 전달: 증상 경보와 소진율 위험 판정
4. 대응•개선 과제 전달: 배포•복구•안정화 우선순위 전환
5. 자동화•학습 결과 전달: 토일 감축•사후 분석 결과 환류

#### 한줄 요약

- 실패 여유가 충분하면 변경하고, 빠르게 소진되면 복구와 안정성 개선을 우선한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **개발•운영(Development and Operations, DevOps)**: 개발과 운영의 협업•자동화•공동 책임을 강조하는 문화와 실천 방식이다.
- **전통 운영**: 승인 절차와 수동 대응을 중심으로 안정 가동을 관리하는 운영 접근법을 말한다.

</details>

SRE는 SLO와 오류 예산을 정량 운영 규칙으로 사용한다.

| 서비스 운영 접근법 | SRE | 전통 운영 | DevOps |
|:---|:---|:---|:---|
| 적용 기준 | **정량적 신뢰성 운영** | **안정 가동•절차 통제** | **개발•운영 협업** 개선 |
| 핵심 특징 | **SLO•오류 예산•자동화** | **승인•수동 대응** 중심 | **공동 책임•빠른 피드백** |
| 한계 | **잘못된 SLO•도입 비용** | **확장성•변경 속도** 한계 | **정량 운영 규칙** 부족 |

#### 한줄 요약

- 개발•운영가 협업 방향이라면 SRE는 신뢰성 목표와 변경 규칙을 실제 운영 방식으로 만든다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **증상 기반 경보**: 내부 원인보다 사용자가 실제 겪는 실패•지연을 기준으로 발생시키는 경보이다.
- **경보 피로**: 과도하거나 조치 불가능한 경보가 반복되어 대응자의 집중력과 반응 품질이 떨어지는 현상을 의미한다.

</details>

SLI와 SLO는 사용자 여정을 대표해야 한다.

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SLO 품질** 미검증 시 내부 지표 중심의 **사용자 영향 왜곡 | 사용자 여정 기반 SLI와 **정기 목표 검토** | SLO **사용자 영향 대표성** 향상 |
| 오류 예산** 미검증 시 정책 부재에 따른 **배포 판단 충돌 | 소진율별 중지•재개•예외 **사전 합의** | 배포 **판단 일관성** 확보 |
| 토일•온콜** 미검증 시 반복 업무•경보의 **담당자 소진 | 토일 측정•자동화와 **증상 기반 경보** | **경보 피로** 감소 |

#### 한줄 요약

- 사용자 신뢰성 목표와 예산 정책을 합의하고 반복 수작업•무효 경보를 자동화 대상으로 관리한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **안정화 우선순위**: 오류 예산이 빠르게 소진될 때 신규 변경보다 복구•자동화•재발 방지를 먼저 수행하는 기준을 의미한다.
- **변경 기준**: 오류 예산 상태에 따라 배포를 계속•중지•재개하도록 사전에 합의한 규칙을 의미한다.

</details>

- **오류 예산** 남으면 배포, 빠르게 소진되면 **안정화**•**자동화** 우선

#### 한줄 요약

- 신뢰성 목표를 수치화하고 실패 여유에 맞춰 배포와 안정화의 우선순위를 바꾼다.
