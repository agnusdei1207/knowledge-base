## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **벡터 데이터베이스(Vector Database)**: 벡터•식별자•메타데이터와 유사도 검색 색인을 함께 관리하는 검색 특화 저장소.
- **근사 최근접 이웃(Approximate Nearest Neighbor, ANN)**: 일부 정확도를 양보하고 탐색량을 줄이는 이웃 검색 방식이다.

</details>

- 정의: 벡터•원문•메타데이터와 ANN 색인을 관리하는 **벡터 DB**
- 배경/필요성: 비정형 텍스트, 이미지, 음성 등으로부터 추출된 수억~수십억 개의 고차원 임베딩 벡터를 전통적인 관계형 데이터베이스(RDB)에 저장하고 선형 전수 탐색(KNN)을 수행할 경우, 데이터 증가에 비례하여 연산량($O(N)$)과 검색 지연이 기하급수적으로 폭증하여 실시간 서비스가 불가능한 한계가 존재함에 따라, 고차원 벡터의 저장, 효율적인 근사 최근접 이웃(ANN: Approximate Nearest Neighbor / HNSW, IVF-PQ) 색인, 메타데이터 필터링 및 분산 확장을 전문적으로 처리하는 벡터 데이터베이스(Vector Database: Milvus, Qdrant, Pinecone, Chroma, pgvector) 기술을 도입하여 **수백만~수억 건의 고차원 벡터에 대해 밀리초(ms) 단위의 초저지연 유사도 검색 실현, 메타데이터 사전/사후 필터링(Filtered Search) 기반의 정밀한 조건부 권한 제어, 데이터의 실시간 CRUD 동기화 및 분산 샤딩을 통한 무제한 수평 확장성(Horizontal Scalability) 확보**를 달성할 필요

#### 한줄 요약
- 근사 색인은 전수 비교 비용을 없애는 대신 정확한 최근접 이웃을 보장하지 않으므로, 벡터 DB 운영은 회수율과 지연 사이에서 색인 파라미터와 **변경 상태** 반영 주기를 고르는 일이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **회수율(Recall)**: 관련 이웃 중 검색 결과가 실제로 찾아낸 비율이다.
- **탐색 폭(Search Breadth)**: ANN이 후보를 찾을 때 조사하는 색인 범위이다.

</details>

- **연결 관리**: 벡터•원문•메타데이터•권한 결합
- **탐색 폭 절충**: 회수율•지연•메모리 조정
- **변경 동기화**: 저장소•색인•복제본에 삽입•수정•삭제 반영

#### 한줄 요약

- **ANN 회수율•필터**와 변경 동기화가 검색 품질 결정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **임베딩(Embedding)**: 텍스트•이미지를 의미나 특징 벡터로 변환한 표현이다.
- **벡터 저장소**: 벡터 식별자와 원문•메타데이터•버전을 함께 보존하는 저장 계층.
- **근사 최근접 이웃 색인(Approximate Nearest Neighbor Index, ANN Index)**: 전체 비교 없이 가까운 후보를 찾는 구조이다.
- **거리 함수(Distance Function)**: 코사인•내적•유클리드 거리 등으로 벡터 간 유사성을 계산하는 함수.
- **메타데이터 필터**: 권한•시간•문서 유형으로 후보를 제한하는 구성요소이다.
- **변경 관리**: 삽입•삭제•재임베딩과 색인 버전을 동기화하는 기능이다.

</details>

```text
                   [변경 관리]
                     /     \
          [벡터 저장소] ----- [근사 색인]
                              /       \
                       [거리 함수]   [필터부]
```

선의 의미: 저장소•근사 색인의 버전을 거리 함수•필터와 함께 관리하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 벡터 저장소 | 벡터•원문•권한•시점 연결 |
| 근사 색인 | 벡터 후보 탐색 범위 축소 |
| 거리 함수 | 벡터 간 유사도 계산 |
| 필터부 | 메타데이터로 허용 후보 제한 |
| 변경 관리 | 저장•색인•복제본 버전 추적 |


#### 한줄 요약
- **저장소•근사 색인**과 거리•필터•변경 관리 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **메타데이터 필터(Metadata Filter)**: 권한•시점•문서 유형으로 후보를 제한하는 구성요소이다.
- **거리 기반 순위**: 질의 벡터와 후보 벡터의 거리•유사도로 이웃 순서를 정하는 개념이다.

</details>

```text
질의 처리기 ── 질의 벡터•필터 조건 ──▶ 메타데이터 필터
                                          │ 1. 사전 필터 범위 적용
                                          ▼
                                       근사 색인
                                          │ 2. ANN 이웃 탐색
                                          │ 3. 거리 기반 후보 순위 산출
                                          ▼
                                    메타데이터 필터
                                          │ 4. 사후 필터•원문 조회
                                          ▼
                                     벡터 저장소
                                          └── 허용 이웃 문서 ──▶ 질의 처리기
```

### 동작 원리

1. 사전 필터 범위 적용: 권한•시점•문서 유형으로 후보 축소
2. ANN 이웃 탐색: 근사 색인으로 가까운 벡터 후보 탐색
3. 거리 기반 후보 순위 산출: 거리 함수로 이웃 순서 결정
4. 사후 필터•원문 조회: 부적합 후보 제거와 원문 결합

#### 한줄 요약
- **사전 필터•ANN** 후 거리 순위•원문 조회 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전용 벡터 데이터베이스(Dedicated Vector Database)**: 벡터 저장과 근사 색인의 독립 확장에 강점이 있는 방식.
- **관계형 데이터베이스 확장(Relational Database Extension)**: 업무 데이터와 벡터의 트랜잭션 일관성에 강점이 있는 방식이다.
- **검색 엔진 벡터(Vector Search Engine)**: 역색인과 벡터를 결합한 희소•밀집 혼합 검색에 강점이 있는 방식.

</details>

데이터베이스(Database, DB) 통합 범위와 근사 최근접 이웃(Approximate Nearest Neighbor, ANN) 검색 신호에 따라 전용 벡터형, 관계형 확장형, 검색 엔진형을 선택한다.

| 저장 방식 | 전용 벡터 DB | 관계형 DB 확장 | 검색 엔진 벡터 |
|:---|:---|:---|:---|
| 적용 기준 | 대규모 **독립 확장** | 업무 **일관성** 우선 | **혼합 검색** 우선 |
| 핵심 특징 | 분산 **ANN 색인** 중심 | 관계 데이터•**벡터 통합** | 역색인•**벡터 통합** |
| 한계 | 원문•색인 **동기화 부담** | 대규모 **벡터 확장 제약** | 두 색인의 **자원 경합** |

#### 한줄 요약
- **독립 확장•업무 일관성**과 혼합 검색에 따라 저장 방식 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **사전 필터(Pre-filter)**: 근사 최근접 이웃(Approximate Nearest Neighbor, ANN) 탐색 전에 허용 후보를 제한하는 방식.
- **사후 필터(Post-filter)**: ANN 결과에서 조건에 맞지 않는 항목을 제거하는 방식이다.
- **색인 전환(Index Cutover)**: 새 색인을 검증한 뒤 읽기 트래픽을 전환하는 절차이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ANN의 **이웃 누락** | 탐색 폭별 **회수율**•**지연** 측정 | 회수율 목표에 맞는 **탐색 폭 결정** |
| 필터 후 **후보 부족** | **사전•사후 필터** 방식 비교 | 조건 검색의 **회수율 보존** |
| 삭제된 **벡터 잔존** | 저장소•색인•복제본 **동기화** | 오래된 **후보 반환 방지** |

#### 한줄 요약
- **이웃 누락•후보 부족**과 삭제 벡터 잔존 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **선택 기준(Selection Criteria)**: 회수율•검색 지연•필터 선택도와 변경 동기화 요구사항.

</details>

- 대규모 고차원 임베딩을 효율적으로 색인하고 밀리초 단위로 회수하여 현대 LLM 및 RAG 시스템의 핵심 영속 계층(Memory Layer)으로 군림한 **생성형 AI 인프라의 최고 핵심 데이터베이스(Vector Database / ANN Index: HNSW & IVF-PQ / Scalar-Vector Hybrid Filtering / ACID Transaction & Distributed Sharding / Dedicated Vector DB: Milvus, Qdrant vs pgvector)의 표준 솔루션**으로 확고히 자리 잡았으며, 멀티모달 및 복합 검색 엔진으로 진화하는 가운데, 실무 벡터 DB 아키텍처 선정 시에는 **대규모 분산 확장성과 초고속 QPS가 요구되는 환경에서는 전용 벡터 DB(Milvus/Qdrant)를 채택하고 기존 RDB 트랜잭션 일관성과 관리 단순성이 중요한 환경에서는 pgvector를 활용하며, 검색 정확도(Recall)와 메모리(VRAM/RAM) 비용 간의 최적 균형을 위해 HNSW/IVF-PQ 파라미터 및 제품 양자화(PQ) 적용**을 결합하여 완벽한 검색 처리량과 경제적인 인프라 안정성을 완성

#### 한줄 요약
- **확장성•일관성**과 검색 신호에 따라 저장 방식 결정
