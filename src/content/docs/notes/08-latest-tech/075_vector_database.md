## 미리 알고가기

- **벡터 DB(Vector Database, 벡터 디비)**: 벡터·식별자·메타데이터와 유사도 검색 색인을 관리하는 저장소
- **ANN(Approximate Nearest Neighbor, 에이엔엔)**: 영문 머리글자를 딴 근사 최근접 이웃 검색으로, 정확도를 일부 양보해 탐색량을 절감
- **DB(Database, 디비)**: 데이터와 변경 상태를 지속 저장·관리하는 시스템
- **임베딩 (Embedding)**: 대상을 벡터로 변환



## Ⅰ. 개요

- 정의/개념: 벡터·메타데이터를 저장하고 근사 검색
- 기존 한계: 대규모 벡터 전수 비교는 검색 시간·연산량 증가
- **배경/필요성**: 근사 색인과 메타데이터 필터의 통합 관리

### 쉽게 이해하기 (학습용)

- 비슷한 벡터를 빨리 찾는 색인과 메타데이터의 변경 상태를 함께 관리합니다.

## Ⅱ. 특징

- 벡터·원문 식별자·메타데이터·권한을 연결해 저장한다.
- ANN 색인으로 회수율과 지연·메모리의 절충을 관리한다.
- 삽입·수정·삭제 시 저장소·색인·복제본을 동기화한다.

### 쉽게 이해하기 (학습용)

- 근사 색인은 빠르지만 가까운 항목을 놓칠 수 있고 필터와 갱신도 성능을 바꿉니다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 저장소 | 벡터와 원문·권한·시점 연결 |
| 근사 색인 | 벡터 후보 탐색 범위 축소 |
| 거리 함수 | 벡터 간 유사도 계산 |
| 필터부 | 메타데이터로 허용 후보 제한 |
| 변경 관리 | 저장·색인·복제본 버전 추적 |

```text
벡터저장
├─ 근사색인
├─ 거리함수
├─ 조건필터
└─ 변경관리
```

### 쉽게 이해하기 (학습용)

- 벡터 저장·근사 색인·필터·변경 관리가 역할을 나눕니다.

## Ⅳ. 원리 및 절차 흐름도

```text
적재검증
  ↓
저장색인
  ↓
질의탐색
  ↓
거리정렬
  ↓
변경반영
```

| 절차 | 설명 |
|:---|:---|
| 적재검증 | 규격·학습 방식·모델 일치 확인 |
| 저장색인 | 벡터·메타데이터 저장 및 색인 |
| 질의탐색 | 필터로 ANN 후보 탐색 |
| 거리정렬 | 후보 거리로 원문 참조 정렬 |
| 변경반영 | 데이터 갱신·삭제 버전 검증 |

### 쉽게 이해하기 (학습용)

- 벡터를 색인해 후보를 찾고 수정·삭제 반영 상태를 확인합니다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 관계형 DB 확장 | 검색 엔진 벡터 | 전용 벡터 DB |
|:---|:---|:---|:---|
| 적용 기준 | 업무 일관성 우선 | 혼합 검색 우선 | 대규모 독립 확장 |
| 핵심 특징 | 관계 데이터·벡터 통합 | 역색인·벡터 통합 | 분산 ANN 색인 중심 |
| 한계 | 대규모 벡터 확장 제약 | 두 색인의 자원 경합 | 원문·색인 동기화 부담 |

### 쉽게 이해하기 (학습용)

- 관계형·검색 엔진·전용 벡터 DB는 통합 범위가 다릅니다.

## Ⅵ. 실무 사례

- 사내 검색: 메타데이터 필터를 탐색과 병행해 허용 문서 반환

### 쉽게 이해하기 (학습용)

- 권한 없는 문서는 제외하고 임베딩 모델을 바꾸면 새 색인을 검증한 뒤 전환합니다.

## Ⅶ. 결론

- 근접 검색을 위해 회수율·지연을 검토하여 **벡터 DB** 활용

### 쉽게 이해하기 (학습용)

- 검색 속도뿐 아니라 이웃 누락과 메모리 사용 및 수정·삭제 반영을 확인해야 합니다.
