## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **올리듀스(All-Reduce)**: 모든 참여자의 값을 합•최댓값 등으로 축약한 뒤 같은 결과를 모든 참여자에게 배포하는 집단 통신 연산을 말한다.
- **집단 통신**: 정해진 참여자 집합이 동일한 호출 순서와 자료형으로 공동 데이터 교환을 수행하는 연산로 정의된다.

</details>

- 정의/개념: 분산 값을 축약하고 동일 결과를 모든 참여자에게 배포하는 **올리듀스 집단 통신**임.
- 배경/필요성: 중앙 집계 서버는 기울기 통신의 **대역폭•처리 병목**을 유발함.

#### 한줄 요약
- 각 조의 숫자를 모두 더한 같은 합계를 중앙 선생님 없이 조끼리 전달해 전원이 받음이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **리듀스-스캐터(Reduce-Scatter)**: 값을 청크로 나누어 축약하면서 각 참여자에게 결과 청크 하나씩을 분산하는 단계이다.
- **올개더(All-Gather)**: 참여자마다 가진 결과 청크를 교환하여 모두가 전체 결과를 갖게 하는 단계을 의미한다.

</details>

![참여자 수에 따른 All-Reduce 통신 단계 수](/study/diagrams/all-reduce-stage-growth.svg)

> 참여자 수가 늘수록 파란 링 단계 수는 가파르게 증가하지만 붉은 트리는 완만해 작은 메시지의 단계 지연에 유리하며, 대역폭•청크 크기를 제외한 이론 비교다.

- **연산 축**: 리듀스-스캐터•올개더 기반 축약•배포함.
- **전송 축**: 청크•버킷으로 다중 링크 병렬 활용임.
- **배치 축**: 알고리즘•순위와 물리 토폴로지 정합임.

#### 한줄 요약
- 큰 짐을 조각내 여러 길로 동시에 합치고 다시 나누어 모두가 같은 결과를 가짐이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **순위(Rank)**: 집단 통신에 참여하는 프로세스•가속기를 구분하는 논리 번호로 정의된다.
- **버킷(Bucket)**: 여러 작은 기울기를 묶어 한 번의 집단 통신으로 보내는 전송 단위을 말한다.
- **집단 통신 토폴로지**: 참여자를 링•트리•계층으로 연결한 논리 통신 경로을 말한다.

</details>

```text
                        [통신자•순위]
                         /          \
                  [축약 연산기]   [청크•버킷 관리자]
                         \          /
                    [집단 통신 알고리즘]
                              |
                       [토폴로지 매퍼]
```
선의 의미: 통신자•순위의 통신 계약은 축약 연산기와 청크•버킷 관리자에 공통으로 적용되고, 집단 통신 알고리즘은 두 구성을 결합해 토폴로지 매퍼가 정한 물리 링크 배치를 사용한다.

| 구성요소 | 책임 |
|:---|:---|
| 통신자•순위 | 참여 집합•자료형•호출 순서의 **통신 계약 관리** |
| 축약 연산기 | 합•평균•최댓값의 **수치 연산 수행** |
| 청크•버킷 관리자 | 메시지 분할•결합의 **전송 단위 조절** |
| 집단 통신 알고리즘 | 링•트리•계층형의 **축약•배포 경로 실행** |
| 토폴로지 매퍼 | 링크 대역폭에 맞는 **순위•경계 배치** |

#### 한줄 요약
- 참가자 번호와 더하는 규칙, 짐 조각 크기, 전달 순서, 실제 길 배치를 모두 맞춰야 한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **청크(Chunk)**: 큰 메시지를 여러 링크에서 병렬로 교환하도록 나눈 데이터 조각이다.
- **역전파(Backpropagation)**: 모델 출력 오차의 기울기를 뒤쪽 층부터 전달하여 가중치 수정값을 계산하는 학습 과정을 의미한다.

</details>

```text
통신 계약 관리자
   │ 1. 참여•자료형•연산 조건 확인
   ▼
작업•버킷 관리자
   │ 2. 기울기 청크•버킷 분할
   ▼
알고리즘 선택기
   │ 3. 메시지•토폴로지별 경로 선택
   ▼
Reduce-Scatter
   │ 4. 청크 축약•분산
   ▼
All-Gather
   └── 5. 결과 청크 교환 ──▶ 통신 계약 관리자
```

1. **참여•자료형•연산 조건 확인**: 모든 순위의 원소 수•형식•호출 순서 **일치 여부**를 검증함.
2. **기울기 청크•버킷 분할**: 지연•대역폭과 역전파 준비 순서에 맞는 **전송 단위**를 구성함.
3. **메시지•토폴로지별 경로 선택**: 크기•참여 수•링크 구조에 맞는 **링•트리•계층 경로**를 결정함.
4. **청크 축약•분산**: 참여자가 청크를 교환•축약해 **분할 결과**를 보유함.
5. **결과 청크 교환**: 분할 결과 교환으로 동일 전체 결과를 생성함.

#### 한줄 요약
- 같은 규격의 짐을 조각내 길에 맞는 순서로 더하고 각자 가진 합계 조각을 다시 교환하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **링 올리듀스(Ring All-Reduce)**: 참여자가 원형 경로로 청크를 순환시켜 축약•배포하는 대역폭 중심 알고리즘을 말한다.
- **트리 올리듀스(Tree All-Reduce)**: 로그 단계의 트리 경로로 값을 축약하고 방송하는 지연 중심 알고리즘이다.

</details>

| 비교 기준 | 링 | 트리 | 계층형 |
|:---|:---|:---|:---|
| 적용 기준 | **큰 메시지•대역폭 활용** | **작은 메시지•단계 축소** | **노드 내외 링크 차이** |
| 핵심 특징 | 청크 순환 **축약•배포** | 로그 단계 **축약•방송** | 노드 내부•외부 **분리 축약** |
| 한계 | **순위 증가 시 단계 증가** | **상위 링크 집중** | **계층 경계•매핑 복잡** |

> 요약: 큰 메시지는 **링**, 작은 메시지는 **트리**, 이종 링크는 **계층형**이 핵심이다.

#### 한줄 요약
- 큰 짐은 원형 길, 빠른 전달은 나무 길, 건물 안팎 속도가 다르면 계층형 길을 선택하는 것이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **집단 교착**: 참여자의 호출 순서•원소 수•자료형이 달라 일부 순위가 영구 대기하는 상태이다.
- **계산•통신 중첩**: 역전파로 준비된 기울기를 즉시 전송해 계산과 데이터 교환을 동시에 진행하는 최적화이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순위별 호출 불일치의 **집단 교착** | 원소•자료형•호출 순서 사전 검증 | 통신 진행 **정합성 확보** |
| 느린 링크를 지난 **링 단계 지연** | 토폴로지 기반 순위 재배치•계층형 적용 | 병목 링크 영향 **완화** |
| 큰 버킷의 **역전파 중첩 지연** | 기울기 준비 순서별 버킷 크기 조정 | 계산•통신 중첩률 **향상** |

#### 한줄 요약
- 모든 조가 같은 순서로 참여하고 느린 길을 피하며 준비된 짐부터 보내도록 묶음 크기를 정하는 것이 핵심이다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **단계 지연**: 집단 통신 알고리즘이 결과를 완성하기 위해 거치는 순차 전송 단계의 누적 시간을 말한다.
- **계층형 올리듀스(Hierarchical All-Reduce)**: 노드 내부와 외부처럼 성능이 다른 링크별로 축약•배포 단계를 나누는 방식이다.

</details>

- **단계 지연•링크 계층**에 따라 링•트리•계층형 올리듀스를 선택함.

#### 한줄 요약
- 짐 크기와 사람 수, 실제 길 구조에 맞춰 링•트리•계층형과 짐 조각 크기를 고름이 핵심 원칙 준수
