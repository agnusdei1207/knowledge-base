## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **올리듀스(All-Reduce)**: 분산된 참여자들의 입력값을 특정 연산(합, 평균, 최댓값 등)으로 축약한 뒤, 동일한 최종 결과를 모든 참여자에게 배포하는 집단 통신 연산 기술.
- **집단 통신(Collective Communication)**: 정해진 참여자 그룹 전체가 동일한 호출 순서와 규격으로 데이터를 교환하여 시스템 전체를 동기화하는 고성능 연산 방식.

</details>

- 정의: 분산 값을 축약해 모든 참여자에게 배포하는 **All-Reduce**이다.
- 배경/필요성: 중앙 집계 서버의 **대역폭•처리 병목** 해소

#### 한줄 요약
- 중앙 서버 없이 **분산 축약•결과 공유** 기반 병렬 동기화

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **리듀스-스캐터(Reduce-Scatter)**: 데이터를 청크 단위로 나누어 축약 연산을 수행하고, 각 참여자에게 부분 축약 결과를 분산 전달하는 기술적 단계.
- **올개더(All-Gather)**: 참여자들이 보유한 부분 축약 결과 청크를 상호 교환하여, 모든 참여자가 최종 축약된 전체 데이터를 확보하는 단계.

</details>

![참여자 수에 따른 All-Reduce 통신 단계 수](/study/diagrams/all-reduce-stage-growth.svg)

> 참여자 수가 늘수록 파란 링 단계 수는 가파르게 증가하지만 붉은 트리는 완만해 작은 메시지의 단계 지연에 유리하며, 대역폭•청크 크기를 제외한 이론 비교다.

- 리듀스-스캐터•올개더 기반 **축약**•**배포**
- 청크•버킷 기반 **다중 링크 병렬 활용**
- 알고리즘•순위와 **물리 토폴로지 정합** #### 한줄 요약
- 리듀스-스캐터와 **올개더** 기반 분산 동기화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **통신자 및 순위(Communicator and Rank)**: 통신에 참여하는 프로세스 그룹과 각 프로세스를 고유하게 식별하는 논리 번호.
- **버킷(Bucket)**: 다수의 그래디언트(Gradient) 데이터를 묶어 단일 집단 통신 단위로 처리하는 데이터 묶음.
- **집단 통신 토폴로지(Collective Communication Topology)**: 물리적 연결 구조를 반영하여 참여자들을 링, 트리, 계층형 등으로 연결하는 논리 통신 경로.

</details>

```text
                        [통신자•순위]
                         /          \
                  [축약 연산기]   [청크•버킷 관리자]
                         \          /
                    [집단 통신 알고리즘]
                              |
                       [토폴로지 매퍼]
```
선의 의미: 통신자•순위의 통신 계약은 축약 연산기와 청크•버킷 관리자에 공통으로 적용되고, 집단 통신 알고리즘은 두 구성을 결합해 토폴로지 매퍼가 정한 물리 링크 배치를 사용한다.

| 구성요소 | 책임 |
|:---|:---|
| 통신자•순위 | 참여 집합•자료형•호출 순서의 **통신 계약 관리** |
| 축약 연산기 | 합•평균•최댓값의 **수치 연산 수행** |
| 청크•버킷 관리자 | 메시지 분할•결합의 **전송 단위 조절** |
| 집단 통신 알고리즘 | 링•트리•계층형의 **축약•배포 경로 실행** |
| 토폴로지 매퍼 | 링크 대역폭에 맞는 **순위•경계 배치** |

#### 한줄 요약
- 통신 계약•연산•전송 단위•**토폴로지 매핑** 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **청크(Chunk)**: 큰 메시지를 여러 링크에서 병렬로 교환하도록 나눈 데이터 조각이다.
- **역전파(Backpropagation)**: 모델 출력 오차의 기울기를 뒤쪽 층부터 전달하여 가중치 수정값을 계산하는 학습 과정을 의미한다.

</details>

```text
통신 계약 관리자
   │ 1. 참여•자료형•연산 조건 확인
   ▼
작업•버킷 관리자
   │ 2. 기울기 청크•버킷 분할
   ▼
알고리즘 선택기
   │ 3. 메시지•토폴로지별 경로 선택
   ▼
Reduce-Scatter
   │ 4. 청크 축약•분산
   ▼
All-Gather
   └── 5. 결과 청크 교환 ──▶ 통신 계약 관리자
```

### 동작 원리

1. 참여•자료형•연산 조건 확인: 원소 수•형식•호출 순서 **일치 여부** 활용 검증함.
2. 기울기 청크•버킷 분할: 지연•대역폭과 역전파 준비 순서에 맞는 **전송 단위** 활용 구성함.
3. 메시지•토폴로지별 경로 선택: 크기•참여 수•링크 구조에 맞는 **링•트리•계층 경로** 활용 결정함.
4. 청크 축약•분산: 참여자가 청크를 교환•축약해 **분할 결과** 활용 보유함.
5. 결과 청크 교환: 분할 결과 교환으로 동일 전체 결과를 생성함.

#### 한줄 요약
- 청크 축약•분산 후 **결과 청크 교환** 기반 전체 결과 생성

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **링 올리듀스(Ring All-Reduce)**: 참여자가 원형 경로로 청크를 순환시켜 축약•배포하는 대역폭 중심 알고리즘을 말한다.
- **트리 올리듀스(Tree All-Reduce)**: 로그 단계의 트리 경로로 값을 축약하고 방송하는 지연 중심 알고리즘이다.

</details>

| 구분 | 링 | 트리 | 계층형 |
|:---|:---|:---|:---|
| 적용 기준 | **큰 메시지•대역폭 활용** | **작은 메시지•단계 축소** | **노드 내외 링크 차이** |
| 핵심 특징 | 청크 순환 **축약**•**배포** | 로그 단계 **축약**•**방송** | 노드 내부•외부 **분리 축약** |
| 한계 | **순위 증가 시 단계 증가** | **상위 링크 집중** | **계층 경계•매핑 복잡** |

> 요약: 큰 메시지는 **링**, 작은 메시지는 **트리**, 이종 링크는 **계층형** 핵심이다.

#### 한줄 요약
- 메시지 크기•링크 계층에 따른 **링•트리•계층형** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **집단 교착**: 참여자의 호출 순서•원소 수•자료형이 달라 일부 순위가 영구 대기하는 상태이다.
- **계산•통신 중첩**: 역전파로 준비된 기울기를 즉시 전송해 계산과 데이터 교환을 동시에 진행하는 최적화이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 순위별 호출 불일치의 **집단 교착** | 원소•자료형•호출 순서 사전 검증 | 통신 진행 **정합성 확보** |
| 느린 링크를 지난 **링 단계 지연** | 토폴로지 기반 순위 재배치•계층형 적용 | 병목 링크 영향 **완화** |
| 큰 버킷의 **역전파 중첩 지연** | 기울기 준비 순서별 버킷 크기 조정 | 계산•통신 중첩률 **향상** |

#### 한줄 요약
- 통신 계약 사전 검증과 **순위•버킷 배치** 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **단계 지연**: 집단 통신 알고리즘이 결과를 완성하기 위해 거치는 순차 전송 단계의 누적 시간을 말한다.
- **계층형 올리듀스(Hierarchical All-Reduce)**: 노드 내부와 외부처럼 성능이 다른 링크별로 축약•배포 단계를 나누는 방식이다.

</details>

- 큰 메시지는 **링**, 작은 메시지는 **트리**, 이종 링크는 계층형 선택

#### 한줄 요약

- 데이터 크기•참여 수•토폴로지에 맞춰 **알고리즘**•**청크** 결정
