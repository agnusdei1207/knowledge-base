## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **모델 컨텍스트 프로토콜 클라이언트(Model Context Protocol Client, MCP Client)**: 호스트 내부에서 하나의 MCP 서버 연결과 자기기술적 JSON-RPC 요청을 관리하는 구성요소다.
- **자바스크립트 객체 표기법 원격 절차 호출(JavaScript Object Notation Remote Procedure Call, JSON-RPC)**: 요청•응답•알림•오류를 JSON 객체로 표현하는 메시지 형식이다.

</details>

- 정의/개념: 서버 연결과 **JSON-RPC** 메시지를 관리하는 **MCP Client**이다.
- 배경/필요성: 서버 직접 연동은 연결•추적 구현이 중복돼 **보안 경계 유지할 수 없다**.

#### 한줄 요약
- 호스트와 서버 사이의 **전담 연결•메시지 중개기**가 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **요청 메타데이터**: 각 요청에 프로토콜 버전•클라이언트 식별•기능을 담아 독립 처리를 가능하게 하는 정보다.
- **요청 식별자(Request Identifier, Request ID)**: 비동기 요청과 그에 대응하는 응답•취소를 연결하는 값이다.

</details>

- **요청 축**: 서버별 연결과 버전•식별•기능 메타데이터를 관리한다.
- **추적 축**: **Request ID**•알림•취소 기반 비동기 상태를 추적한다.
- **중계 축**: 기능 명세•실행 결과를 호스트에 전달한다.

#### 한줄 요약
- 서버별 **독립 연결•Request ID**로 결과를 호스트에 중계가 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메시지 디스패처**: JSON-RPC 식별자와 메시지 유형을 이용해 응답•알림•오류를 해당 요청과 처리기로 전달한다.
- **요청 메타 관리자**: 요청마다 프로토콜 버전•클라이언트 식별•기능을 구성하는 요소다.
- **기능 변환기**: 서버가 공개한 도구•리소스•프롬프트 명세를 호스트가 사용할 수 있는 형태로 전달하는 구성요소이다.
- **전송 관리자**: 로컬•원격 연결을 열고 메시지 프레이밍과 연결 상태를 관리하는 구성요소이다.
- **표준 입출력(Standard Input/Output, stdio)**: 로컬 클라이언트와 서버가 프로세스 입출력 스트림으로 메시지를 교환하는 전송 방식이다.
- **스트리밍 가능 하이퍼텍스트 전송 프로토콜(Streamable Hypertext Transfer Protocol, Streamable HTTP)**: 원격 요청을 HTTP POST와 메서드•기능 라우팅 헤더로 교환하는 전송 방식이다.

</details>

- **메시지 디스패처** 중심 구조는 **JSON-RPC** 메시지를 분배하고 **stdio** 또는 **Streamable HTTP** 연결을 관리한다.

```text
                    [메시지 중개기]
                   /       |       \
       [요청 메타 관리자] [기능 변환기] [전송 관리자]
```

선의 의미: 메시지 중개기는 요청 메타, 기능 명세, 서버 연결을 하나의 요청•응답 경계로 결합한다.

| 구성요소 | 책임 |
|:---|:---|
| 요청 메타 관리자 | **버전•클라이언트 식별•기능** 구성 |
| 메시지 중개기 | **요청 ID 기반 요청•응답 연결** |
| 기능 변환기 | 호스트 대상 **서버 기능 명세 전달** |
| 전송 관리자 | **stdio•Streamable HTTP 연결** 관리 |

#### 한줄 요약
- **메시지•메타•기능•전송 관리자**가 연결 책임 분담이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **호출 식별자**: 비동기 JSON-RPC 요청과 나중에 도착한 응답을 정확히 연결하는 값이다.
- **모델 컨텍스트 프로토콜 호스트(Model Context Protocol Host, MCP Host)**: 사용자 정책과 여러 MCP Client 연결을 관리하는 AI 애플리케이션이다.

</details>

- **MCP Host•MCP Client•MCP Server** 사이에서 **JSON-RPC** 요청과 응답을 중계한다.

```text
MCP 호스트
   │ 선택 기능•인자•정책 전달
   ▼
MCP 클라이언트
   │ 1. 버전•식별•기능 메타 구성
   │ 2. Request ID 기반 표준 요청 전송
   ▼
MCP 서버
   │ 3. 서버 결과•오류 반환
   ▼
MCP 클라이언트
   │ 4. 출처가 구분된 결과 전달
   ▼
MCP 호스트
```

1. **버전•식별•기능 메타 구성**: 요청마다 프로토콜 버전과 클라이언트 정보를 포함한다.
2. **Request ID 기반 표준 요청 전송**: 선택 기능과 구조화 인자를 전달한다.
3. **서버 결과•오류 반환**: 요청 식별자와 실행 결과를 연결한다.
4. **출처가 구분된 결과 전달**: 서버 경계를 표시해 호스트에 중계한다.

#### 한줄 요약
- 서버 결과를 **Request ID•출처 경계**와 함께 호스트에 전달한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **스트리밍 가능 하이퍼텍스트 전송 프로토콜 클라이언트(Streamable Hypertext Transfer Protocol Client, Streamable HTTP Client)**: HTTP POST와 라우팅 헤더로 원격 MCP 서버와 통신하는 클라이언트다.

</details>

- **MCP Client**와 **MCP Server** 역할을 연결 중개와 기능 제공 기준으로 구분한다.

| 판단 기준 | MCP Client | MCP Server |
|:---|:---|:---|
| 적용 기준 | 호스트의 **서버 연결** | 백엔드 **기능 공개** |
| 핵심 특징 | 서버별 **연결•메시지 중개** | **도구•리소스•프롬프트** 제공 |
| 한계 | 호스트의 **사용자 정책•실행 권한 책임** | 서버의 **권한•입력 검증 책임** |

> 요약: 연결 중개에는 **MCP 클라이언트**, 기능 제공에는 **MCP 서버**를 적용한다.

#### 한줄 요약
- **MCP Client**는 연결 중개, **MCP Server**는 기능을 제공한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **재요청 정책**: 통신 장애 후 백오프•재시도 상한•멱등성으로 중복 실행을 통제하는 규칙이다.
</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 복수 서버 결과 혼합으로 **출처 오인** | 서버별 **독립 연결•출처 식별자** 유지 | 문맥•권한 경계 보존 |
| 연결 중단으로 **미완료 요청 잔존** | **Request ID•취소•시간초과** 기반 상태 정리 | 유실•중복 실행 방지 |
| 기능 변경으로 **허용 정책 불일치** | **캐시 TTL•목록 변경 알림** 후 정책 재평가 | 변경 기능의 안전한 반영 |

#### 한줄 요약
- 서버별 **독립 연결•허용 정책**으로 기능 범위를 통제한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **호스트 중계**: 클라이언트가 서버 기능 명세와 실행 결과를 호스트에 전달하고 최종 사용 여부는 호스트가 결정하게 하는 책임 분리다.

</details>

- 서버 연결•메시지 중계에는 **MCP Client**, 기능 공개에는 **MCP Server**을 선택한다.

#### 한줄 요약
- 서버별 **연결•출처 경계**로 문제 확산을 방지한다.
