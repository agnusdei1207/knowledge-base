## 미리 알고가기

- **GPU 클러스터(Graphics Processing Unit Cluster)**: 다수의 GPU 서버를 고속망·공유 저장소로 연결해 분산 학습과 대규모 추론을 수행하는 인프라
- **성능 결정 요인**: 성능 핵심은 GPU 개수보다 노드 간 통신 효율과 스케줄링과 저장소 연계에 있음
- **활용률**: 활용률과 스케일링 효율과 장애 복원력이 운영 품질 지표가 됨


## Ⅰ. 개요

- 정의/개념: GPU 서버를 고속망으로 묶은 병렬 인프라
- **배경/필요성**: 단일 GPU 서버만으로 모델·배치의 메모리와 학습 처리량 요구 충족 곤란

### 쉽게 이해하기 (학습용)

- 한 작업대에 올릴 수 없는 거대한 모형을 여러 작업대에 나누되, 작업자들이 중간 결과를 주고받는 시간까지 함께 설계하는 공장과 같음

## Ⅱ. 특징

- 데이터·텐서·파이프라인의 **병렬 분할**
- 계산·통신 중첩과 **토폴로지 배치**
- 갱 스케줄링·저장소 기반 **GPU 대기 최소화**

### 쉽게 이해하기 (학습용)

- 작업자를 늘려도 부품 전달과 작업대 배치가 느리면 기다리는 시간이 늘어나므로, 계산과 통신을 겹치고 가까운 작업자를 한꺼번에 배치해야 함

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| GPU 연산 노드 | GPU·호스트·메모리 묶음의 배치·장애 단위 |
| 고속 패브릭 | 노드 간 기울기·파라미터 전송 경로 |
| 집단 통신 계층 | 분산 전략에 따른 작업 분할과 데이터 교환 제어 |
| 스케줄러 | 통신 인접성을 반영한 GPU 동시 할당 |
| 체크포인트 저장소 | 일관된 상태 저장과 분산 복구 경계 |

```text
스케줄러
  │
[GPU 노드A]─┐
[GPU 노드B]─┼─ 고속 패브릭
[GPU 노드N]─┘
  │
체크포인트 저장소
```

> 요약: GPU 인접 배치와 분산 실행·복구를 조정한다.

### 쉽게 이해하기 (학습용)

- 작업 배정표인 스케줄러가 가까운 작업대를 묶고, 전달 통로인 패브릭과 공용 창고인 저장소가 중간 결과와 복구 자료를 이어 줌

## Ⅳ. 원리 및 절차 흐름도

```text
작업 요구 분석 → 병렬 전략·노드 수 결정 → 토폴로지 기반 동시 배치
                                                    ↓
                                          샤드 적재·계산
                                                    ↓
                                         집단 통신·동기화
                                                    └─ 다음 단계 → 샤드 적재·계산
```

| 절차 | 설명 |
|:---|:---|
| 작업 분석 | 모델 메모리와 통신량 산정 |
| 병렬 전략 결정 | 데이터·텐서·파이프라인 분할과 노드 수 결정 |
| 동시 배치 | 통신 인접성을 고려해 GPU 함께 할당 |
| 샤드 적재 | 노드 메모리에 데이터·모델 조각 배치 |
| 계산·통신 중첩 | 역전파와 기울기 통신을 겹쳐 지연 시간 감소 |
| 상태 저장·복구 | 설정 주기마다 분산 저장 후 장애 발생 시 재개 |

> 요약: 작업량으로 배치해 샤드 계산·통신을 반복한다.

### 쉽게 이해하기 (학습용)

- 작업 크기와 전달량을 먼저 계산해 가까운 작업대를 한꺼번에 배정하고, 계산 중간에 결과를 저장해 작업대가 고장 나도 그 지점부터 다시 시작함

## Ⅴ. 가속기 인프라 구성 비교

| 구분 | 단일 GPU 서버 | GPU 클러스터 | 전용 가속기 클러스터 |
|:---|:---|:---|:---|
| 확장 단위 | 한 서버 내 GPU | 여러 GPU 서버 | 고정 토폴로지 가속기 |
| 적용 기준 | 내부 통신으로 처리 시 | 분산 효과가 통신 비용 상쇄 시 | 고정 규모·생태계 충족 시 |
| 핵심 특징 | 서버 내부 고속 연결 | 다중 서버 고속망 분산 | 특정 가속기·컴파일러 통합 |
| 한계 | 메모리·처리량 상한 | 통신·스케줄링 병목 | 생태계·워크로드 제약 |
| 병목 | 메모리·내부 연결 | 집단 통신·저장소 | 컴파일·생태계 종속성 |

> 요약: 단일·GPU·전용 클러스터를 규모로 고른다.

### 쉽게 이해하기 (학습용)

- 한 방에서 끝나는 작업은 단일 서버가 단순하고, 여러 방의 전달 비용보다 분담 효과가 클 때 GPU 클러스터를 사용하며, 정해진 도구만 계속 쓰면 전용 가속기 클러스터가 적합함

## Ⅵ. 실무 사례

1. 대형 모델 학습 클러스터는 역전파와 기울기 집단 통신을 중첩하고 노드 추가 후 단계 시간이 줄지 않으면 확장을 중단함
2. 장기 학습 작업은 분산 체크포인트를 공유 저장소에 기록하고 장애 노드를 교체해 마지막 체크포인트부터 재개함

### 쉽게 이해하기 (학습용)

- 대형 모델은 계산하는 동안 기울기를 주고받아 작업자를 늘린 효과가 전달 대기보다 클 때만 확장하고, 고장 시에는 공동 저장본부터 이어서 학습함

## Ⅶ. 결론

- 병렬 이득이 통신 비용보다 클 때 확장한다

### 쉽게 이해하기 (학습용)

- 작업대를 많이 놓는 것보다 전달 대기와 복구 시간을 포함해 실제 완료 시간이 줄어드는 범위까지만 늘리는 것이 핵심임
