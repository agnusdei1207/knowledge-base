## 미리 알고가기

- **인공지능 기반 IT 운영(Artificial Intelligence for IT Operations, AIOps)**: 영문 핵심 글자를 조합한 표기로 “에이아이옵스”로 읽으며, 운영 신호를 분석해 사건·원인·조치를 지원하는 체계
- **서비스 토폴로지(Service Topology)**: 서비스 구성요소와 호출·의존 관계를 나타낸 연결 지도
- **런북(Runbook)**: 장애 유형별 진단·복구 절차와 실행 조건을 정한 운영 지침

## Ⅰ. 개요

- **정의/개념**: AI로 운영 신호의 사건·원인·조치를 분석한다
- **배경/필요성**: 고정 임계값·개별 경보만으로 분산 시스템의 경보 폭주와 장애 상관관계 분석 곤란

### 쉽게 이해하기 (학습용)

- 흩어진 사고 경보를 하나의 사건으로 묶고 의심 원인과 허용된 대응을 알려 주는 운영 보조원이다.

## Ⅱ. 특징

- 다중 신호·토폴로지 기반 **경보 상관분석**
- 동적 정상 기준 기반 **이상 탐지**
- 원인 후보·런북·승인 기반 **대응 우선순위**

### 쉽게 이해하기 (학습용)

- 평소와 다른 신호를 찾아 관련 경보를 한 사건으로 묶고 원인 후보와 허용된 복구 수단을 함께 제시한다.

## Ⅲ. 아키텍처 및 구성요소

```text
[관측 데이터] ───────┐
                     ├─> [사건 분석·원인 추정] ──> [런북·정책 제어기]
[서비스 토폴로지] ───┘
```

| 설계 요소 | 설명 |
|:---|:---|
| 관측 데이터 | 로그·메트릭·트레이스·이력 |
| 서비스 토폴로지 | 의존 관계·사건 영향 범위 |
| 사건 분석 엔진 | 경보 군집·이상 패턴 탐지 |
| 원인 추정 모델 | 원인 후보·근거 순위화 |
| 런북·정책 제어기 | 조치·위험·승인·이력 관리 |

> 요약: 관측 신호와 토폴로지로 사건·원인·조치를 잇는다

### 쉽게 이해하기 (학습용)

- 관측 수집·토폴로지·사건 분석·원인 추정·정책 제어가 역할을 나눠 장애 대응을 지원한다.

## Ⅳ. 원리 및 절차 흐름도

```text
신호 정규화 → 사건 탐지 → 원인 후보 산출
                           ↓
                     조치 위험 판정
            ├─ 저위험·승인 런북 → 자동 실행
            └─ 그 외 → 운영자 승인 후 실행
                           ↓
                     검증 및 피드백
```

| 절차 | 설명 |
|:---|:---|
| 관측 신호 정규화 | 데이터를 시간·식별자로 정렬 |
| 사건·이상 탐지 | 경보 군집·정상 이탈 탐지 |
| 원인 후보 산출 | 후보별 근거·영향 범위 제시 |
| 조치 위험 판정 | 자동 실행·운영자 승인 선택 |
| 결과 검증·피드백 | 복구 확인·이력 반영 |

> 요약: 신호로 원인 후보를 좁히고 위험별 조치를 선택한다

### 쉽게 이해하기 (학습용)

- 경보를 사건으로 묶고 원인 후보를 좁힌 뒤 저위험 조치는 자동화하고 큰 조치는 운영자 승인을 받는다.

## Ⅴ. IT 운영 분석 방식 비교

| 구분 | 규칙 기반 운영 | AIOps |
|:---|:---|:---|
| 적용 기준 | 단순·안정 운영 환경 | 분산·고변경 운영 환경 |
| 핵심 특징 | 고정 임계값·개별 경보 | 동적 기준·경보 군집 |
| 한계 | 경보 폭주·상관 누락 | 오탐·원인 후보 과신 |

> 요약: 규칙은 단순 환경, AIOps는 복합 상관에 적합하다

### 쉽게 이해하기 (학습용)

- 규칙 기반은 경보별 고정 기준을 보고 AIOps는 여러 신호의 시간·서비스 관계를 하나의 사건으로 해석한다.

## Ⅵ. 실무 사례

1. 서비스 토폴로지로 중복 경보와 원인을 분석한다
2. 저위험 재시작만 자동화하고 변경은 승인받는다

### 쉽게 이해하기 (학습용)

- 결제 장애의 경보를 한 사건으로 묶고 최근 배포와 서비스 의존성을 원인 근거로 제시한다.
- 승인된 재시작 런북만 자동 실행하고 서비스 전환·데이터 변경은 운영자가 승인한다.

## Ⅶ. 결론

- 경보 폭주에 적용하고 자동 조치는 런북으로 제한한다.

### 쉽게 이해하기 (학습용)

- AI가 원인 후보를 빨리 좁혀도 확정으로 믿지 말고 위험한 복구 조치는 사람이 최종 결정해야 한다.
