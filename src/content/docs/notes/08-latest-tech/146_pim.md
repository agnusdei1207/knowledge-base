## 미리 알고가기

- **PIM (Processing-in-Memory)**: 메모리 내·근접 회로에서 연산을 수행해 데이터 이동 비용을 절감하는 구조
- **메모리 병목**: AI와 데이터 분석 워크로드에서 성능 제약을 야기하는 메모리 이동 부하
- **핵심 가치**: 범용성보다 데이터 이동 비용 절감과 에너지 효율 향상에 집중함



## Ⅰ. 개요

- **정의/개념**: 메모리 내부·근처에서 연산해 데이터 이동을 줄인다
- **배경/필요성**: 데이터 왕복의 지연·에너지 병목을 완화한다

### 쉽게 이해하기 (학습용)

- 모든 데이터를 처리기로 옮기지 않고 메모리 안이나 근처에서 계산해 결과만 전달한다.

## Ⅱ. 특징

- 데이터 이동 병목이 큰 작업일수록 효과가 커진다
- 제한된 지원 연산은 범용 프로그램 실행을 어렵게 한다
- 이동 절감이 제어 비용보다 커야 성능 이득이 난다
- 셀 연산 오차는 모델 정확도 저하로 이어질 수 있다
- 배치·일관성 관리는 잘못된 결과 회수를 막는다

### 쉽게 이해하기 (학습용)

- 호스트와 명령을 주고받는 비용보다 데이터 운반을 줄이는 이득이 큰 작업에 적용한다.

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 실행 배치 계층 | 호스트와 PIM 연산 실행 주체 결정 |
| 명령 인터페이스 | 데이터 대상·연산·동기화 명령 전달 |
| 메모리 저장 영역 | 연산 대상 데이터를 연산부 인근 배치 |
| PIM 연산부 | 지원 연산 수행 및 부분 결과 저장 |
| 결과 검증부 | 데이터 소유권과 연산 결과 오차 확인 |

> 요약: 실행 배치·명령·메모리 연산·결과 검증을 연결한다

### 쉽게 이해하기 (학습용)

- 호스트가 지원 작업을 나누고 명령을 보내면 메모리 근처 연산부가 계산하고 검증부가 결과를 확인한다.

## Ⅳ. 원리 및 절차 흐름도

```text
작업 분석
    ↓
오프로딩 판정
    ↓
데이터 배치
    ↓
메모리 연산
    ↓
결과 검증
```

| 절차 | 설명 |
|:---|:---|
| 작업 분석 | 이동량·연산량·재사용률 측정 |
| 오프로딩 판정 | 지원 명령·이동 절감 확인 |
| 데이터 배치 | 대상 데이터를 연산부 인근 배치 |
| 메모리 연산 | 필터·벡터·누산 수행 |
| 결과 검증 | 정확성 확인 뒤 결과 회수 |

> 요약: 이동 이득을 판정해 연산하고 검증된 결과만 회수한다

### 쉽게 이해하기 (학습용)

- 작업의 이동 비용을 분석해 이득이 있는 지원 연산만 메모리로 보내고 정확한 결과만 회수한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 메모리 셀 연산 | 로직 계층 PIM | 메모리 근처 연산 |
|:---|:---|:---|:---|
| 연산 위치 | 셀·감지 회로 동작 | 메모리 은행 내부 디지털부 | 메모리 옆 별도 처리기 |
| 적합 작업 | 허용 오차 대량 행렬·논리 | 필터·벡터·누산 지원 명령 | 복잡한 메모리 집약 작업 |
| 프로그래밍 | 소자 편차·변환 오차 보정 필요 | 제한 명령·배치·일관성 관리 | 유연하지만 근거리 이동 잔존 |

> 요약: 셀은 효율, 로직은 명령, 근처 연산은 유연성을 본다

### 쉽게 이해하기 (학습용)

- 셀 연산은 효율과 오차, 로직 계층은 지원 명령, 메모리 근처 처리는 유연성과 이동량으로 선택한다.

## Ⅵ. 실무 사례

1. 데이터 필터를 메모리 안에서 수행해 이동을 줄인다
2. 추천 벡터 연산은 PIM에서 수행하고 오차 시 복귀한다

### 쉽게 이해하기 (학습용)

- 데이터 분석은 조건에 맞지 않는 행을 메모리에서 먼저 버려 호스트로 옮길 양을 줄인다.
- 추천 추론은 지원 벡터 연산만 PIM에 맡기고 오차 한도를 넘으면 호스트 연산으로 되돌린다.

## Ⅶ. 결론

- 이동 절감이 제어 비용보다 크고 정확할 때 PIM을 적용한다.

### 쉽게 이해하기 (학습용)

- 데이터 운반을 줄인 이득이 명령·동기화 비용보다 크고 결과 오차가 허용 범위일 때만 PIM을 쓴다.
