## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 관측성(Agent Observability)**: 추적•지표•로그를 연계하여 에이전트의 내부 상태와 실패 원인을 파악하는 능력으로 정의된다.
- **종단 경로(End-to-end Trajectory)**: 사용자 목표의 시작부터 모델•도구 호출과 최종 결과까지 이어지는 전체 실행 흐름이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.

</details>

- 정의/개념: 계획•모델•도구의 신호를 연결하는 **에이전트 관측성**
- 배경/필요성: 다단계 호출의 최종 결과만으로 품질 저하•오류•비용 발생 구간을 추적하기 어려움.

#### 한줄 요약

- **종단 경로**에서 지연•오류•비용 발생 위치 식별

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **추적(Trace)**: 하나의 사용자 목표를 처리한 종단 간 실행을 연결한 기록이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **구간(Span)**: 모델 호출이나 도구 실행처럼 추적을 구성하는 개별 작업 단위를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **의미 규약(Semantic Convention)**: 서로 다른 구성요소가 생성한 관측 필드의 이름과 의미를 통일하는 규약으로 정의된다.
- **서비스 수준 목표(Service Level Objective, SLO)**: 지연•오류•비용 같은 운영 지표가 달성해야 하는 목표 수준을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.

</details>

- **추적**: 사용자 목표의 종단 실행 기록 연결
- **구간**: 모델•도구의 개별 작업 단위 기록
- **의미 규약**: 관측 필드 이름•의미 통일
- **SLO**: 지연•오류•비용 목표 위반 식별
- **버전 연계**: 품질 회귀와 변경 원인 연결
- **샘플링**: 저장 비용•개인정보 노출 절충

#### 한줄 요약

- 공통 **Trace ID•의미 규약**으로 모델•도구 기록 연결

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **계측기(Instrumentation)**: 각 호출의 지연•오류•토큰•비용과 추적 문맥을 관측 신호로 생성하는 기능을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **신호 저장소(Signal Storage)**: 추적•지표•로그를 공통 식별자로 연결해 검색•집계할 수 있도록 보존하는 저장소를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **분석•경보기(Analyzer/Alerter)**: 저장된 신호에서 품질 저하•오류•비용 이상과 원인 구간을 분석하여 알리는 구성요소를 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **구조적 로그(Structured Log)**: 사건의 필드를 정해진 형식과 상관 식별자로 기록하여 검색•집계를 가능하게 한 로그로 정의된다.
- **샘플링(Sampling)**: 전체 실행 중 분석 가치가 높은 일부 기록을 선택해 수집 비용을 줄이는 방식을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

```text
                    [계측기]
                        |
                  [수집•처리기]
                        |
                  [신호 저장소]
                        |
                  [분석•경보기]
```

선의 의미: 계측기가 생성한 관측 신호를 수집•처리기와 신호 저장소가 연결하고, 분석•경보기가 공통 신호를 이용하는 관측성 구조를 뜻함.

| 구성요소 | 책임 |
|:---|:---|
| 계측기 | **계측기**가 호출별 추적 구간•운영 지표와 **구조적 로그**를 생성함 |
| 수집•처리기 | **수집•처리기**가 상관 문맥 전파•마스킹•**샘플링**을 수행함 |
| 신호 저장소 | **신호 저장소**가 추적•지표•로그 연계를 보존함 |
| 분석•경보기 | **분석•경보기**가 병목•오류•비용 이상을 탐지함 |

#### 한줄 요약

- **계측•수집•저장•분석 계층**으로 이상 구간 경보

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상관 문맥(Correlation Context)**: 부모•자식 구간과 분산 호출이 같은 실행에 속함을 식별하도록 함께 전달하는 정보를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.
- **성능 회귀(Performance Regression)**: 모델•프롬프트•도구 변경 이후 품질•지연•비용 지표가 이전보다 나빠지는 현상을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **목표•호출별 추적 구간 생성(Goal/Call Trace Span Generation)**: 사용자 목표와 각 모델•도구 호출에 공통 식별자와 구간을 부여하는 절차로 정의된다.
- **지연•오류•토큰•비용 전송(Latency/Error/Token/Cost Transmission)**: 각 구간의 운영 지표와 사건 정보를 수집 계층에 보내는 절차이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **민감정보 보호•표본 집계(Sensitive Data Protection/Sample Aggregation)**: 마스킹과 샘플링을 적용한 관측 신호를 집계하는 절차로 정의된다.
- **부모•자식 구간•버전 연계(Parent/Child Span/Version Linking)**: 상관 문맥과 버전 속성으로 분산 구간과 변경 원인을 연결하는 절차를 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

```text
에이전트
   │ 1. 목표•호출별 추적 구간 생성
   ▼
계측기
   │ 2. 지연•오류•토큰•비용 전송
   ▼
수집•처리기
   │ 3. 민감정보 보호•표본 집계
   │ 4. 부모•자식 구간•버전 연계
   ▼
분석•경보기
   │ SLO 위반 원인 구간 경보
   ▼
에이전트
```

### 동작 원리

1. **목표•호출별 추적 구간 생성**: 공통 추적 식별자로 **종단 경로**를 구성함.
2. **지연•오류•토큰•비용 전송**: 모델•도구 단계의 신호를 수집함.
3. **민감정보 보호•표본 집계**: 마스킹•샘플링으로 비용과 노출을 통제함.
4. **부모•자식 구간•버전 연계**: 변경과 **성능 회귀**를 연결함.

#### 한줄 요약

- **상관 문맥•버전 속성**으로 SLO 위반 원인 식별

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **관측 로그(Observability Log)**: 장애와 성능 원인을 분석하도록 추적•지표•이벤트를 연계하고 집계하는 운영 기록이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **감사 로그(Audit Log)**: 책임과 규정 준수를 입증하도록 주체•행위•결과를 변조하기 어렵게 보존하는 증거 기록을 의미하며, 시스템의 자율적 판단과 실행을 가능하게 하는 핵심 아키텍처 요소이다.

</details>

| 기록 체계 | 에이전트 관측성 | 감사 로그 |
|:---|:---|:---|
| 적용 기준 | 운영 개선•장애 원인 분석 시 적용 | 조사•감사•책임 입증 시 적용 |
| 핵심 특징 | **관측 로그**의 연계•집계를 수행 | **감사 로그**의 무결성을 보존 |
| 한계 | 샘플링 누락•정보 노출•저장 비용 존재 | 실시간 성능 분석 부족 |

#### 한줄 요약

- 원인 분석은 **관측성**, 책임 입증은 **감사 로그**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **적응형 샘플링(Adaptive Sampling)**: 오류•고위험 사건은 전부 수집하고 정상 사건은 비율을 낮춰 저장 비용을 통제하는 방식을 말하며, 실무적 관점에서 안정성과 효율성을 보장하는 주요 기전으로 작용한다.
- **마스킹(Masking)**: 로그의 민감한 원문을 분석에 불필요한 부분만 가려 개인정보 노출을 줄이는 처리이며, 이는 구조적 완결성을 높이고 차별화된 성능을 제공하는 기술적 기반이 된다.
- **버전 속성(Version Attribute)**: 성능 변화를 원인 변경과 연결하도록 모델•프롬프트•도구•정책 버전을 구간에 기록한 값으로 정의된다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모델•도구 간 **상관 문맥** 단절 | **의미 규약**으로 구간을 연결함 | 종단 실행 원인 경로를 재구성함 |
| 원문 프롬프트의 개인정보 노출 | **마스킹**•해시•접근통제를 적용함 | 분석 가능성과 정보 보호 균형을 달성함 |
| 전량 수집의 저장•처리 비용 | 위험별 **적응형 샘플링**을 적용함 | 핵심 사건 보존과 비용을 통제함 |
| 버전 미기록에 따른 회귀 원인 불명 | **버전 속성** 기록을 수행함 | 변경별 **성능 회귀** 추적을 수행함 |

#### 한줄 요약

- **검색•도구 Span**에서 지연 원인 구간 탐지

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 기반 관측(Risk-based Observability)**: SLO와 사건 위험도에 따라 추적 상세도•마스킹•샘플링 수준을 다르게 적용하는 방식으로 정의된다.

</details>

- **SLO•사건 위험도**에 따라 추적•마스킹•샘플링 결정

#### 한줄 요약

- 오류•고위험은 **전수 수집**, 정상 사건은 표본 수집
