## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **데이터 레이크하우스(Data Lakehouse)**: 데이터 레이크의 개방형 파일 저장에 웨어하우스의 원자성•일관성•격리성•지속성(Atomicity, Consistency, Isolation, Durability, ACID) 테이블 관리 기능을 결합한 아키텍처이다.
- **원자성•일관성•격리성•지속성(Atomicity, Consistency, Isolation, Durability, ACID)**: 트랜잭션이 보장해야 하는 네 가지 성질이다.

</details>

- 정의/개념: 개방형 파일 저장소에 **ACID 테이블 관리**를 결합한 **데이터 레이크하우스**이다.
- 배경/필요성: 레이크•웨어하우스 분리는 데이터 복제•버전 불일치와 **파이프라인 중복**을 유발한다.
#### 한줄 요약

- **워크로드 통합**: 분석•스트리밍•기계학습이 동일 테이블을 공유해 정합성을 유지한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **오픈 테이블 포맷(Open Table Format)**: 파일 위에 스키마•스냅샷•트랜잭션 메타데이터를 정의해 여러 엔진이 공유하게 하는 형식이다.
- **스냅샷(Snapshot)**: 특정 시점에 유효한 데이터 파일•스키마•통계의 일관된 테이블 상태이다.
- **비즈니스 인텔리전스(Business Intelligence, BI)**: 데이터를 분석해 의사결정용 보고•지표를 제공하는 활동이다.
- **기계학습(Machine Learning, ML)**: 데이터에서 규칙을 학습해 예측•분류를 수행하는 기술이다.

</details>

- 개방형 저장소•컴퓨트 분리 기반 **다중 엔진 선택권**이 핵심이다.
- **오픈 테이블 포맷** 기반 스키마 진화와 **ACID•스냅샷 관리**가 핵심이다.
- **카탈로그** 기반 BI•스트리밍•ML 통합과 **파일 최적화 부담**이 핵심이다.
#### 한줄 요약

- 여러 엔진이 같은 파일을 공유하되 스냅샷으로 일관된 시점을 읽고 파일•통계를 계속 최적화한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **카탈로그(Catalog)**: 테이블 이름을 현재 메타데이터 위치와 연결하고 원자 커밋을 조정하는 관리 계층이다.
- **오브젝트 데이터 파일**: 개방형 열 지향 형식으로 실제 테이블 데이터를 저장한 객체이다.
- **구조화 질의 언어(Structured Query Language, SQL)**: 관계형 데이터의 정의•조회•변경에 사용하는 질의 언어이다.

</details>

```text
                         [컴퓨트 엔진]
                               |
                           [카탈로그]
                               |
                       [오픈 테이블 포맷]
                          /           \
              [오브젝트 데이터 파일]   [거버넌스•최적화]
```
선의 의미: 컴퓨트 엔진은 카탈로그를 통해 현재 오픈 테이블 포맷 상태를 참조하고, 오픈 테이블 포맷은 오브젝트 데이터 파일의 논리 테이블 경계와 거버넌스•최적화의 품질•유지관리 경계를 결합한다.

| 구성요소 | 책임 |
|:---|:---|
| 컴퓨트 엔진 | SQL•배치•스트리밍•ML의 **읽기•쓰기 실행** |
| 카탈로그 | 테이블 식별자와 **현재 메타데이터 위치 연결** |
| 오픈 테이블 포맷 | 트랜잭션•스키마와 **스냅샷•파일 목록** 관리 |
| 오브젝트 데이터 파일 | 개방형 열 지향 형식의 **데이터 저장** |
| 거버넌스•최적화 | 품질•접근 통제와 **파일•통계 유지관리** |

#### 한줄 요약

- 파일 저장소 위의 테이블 포맷과 카탈로그가 상태를 관리하고 각 엔진이 계산을 수행한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **원자 커밋**: 기준 버전 충돌을 확인한 뒤 현재 메타데이터 포인터를 한 번에 바꾸는 연산이다.
- **후보 스냅샷**: 새 데이터 파일•스키마•통계를 포함하지만 아직 카탈로그에 확정되지 않은 테이블 상태이다.

</details>

```text
[쓰기 엔진] ── 1. 신규 데이터 파일 ──▶ [데이터 파일]
      │ 2. 후보 스냅샷
      ▼
[테이블 메타데이터]
      │ 3. 원자 커밋 요청
      ▼
  [카탈로그]
      │ 4. 확정 스냅샷
      ▼
 [읽기 엔진] ── 5. 유효 파일 조회 ──▶ [데이터 파일]
```

**동작 원리**

1. **신규 데이터 파일 전달**: 변경 결과를 기존 파일 덮어쓰기 없이 새 파일로 생성한다.
2. **후보 스냅샷 전달**: 스키마•통계•유효 파일 목록을 새 메타데이터로 구성한다.
3. **원자 커밋 요청 전달**: 기준 버전 충돌 검증 후 현재 메타데이터 위치를 원자를 갱신한다.
4. **확정 스냅샷 전달**: 독자에게 완전히 확정된 이전•신규 상태 중 하나를 공개한다.
5. **유효 파일 조회 전달**: 읽기 엔진이 선택한 스냅샷의 파일만 일관되게 처리한다.

#### 한줄 요약

- 신규 파일•후보 스냅샷 생성 후 원자 커밋 기반 일관된 조회가 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **데이터 레이크**: 원시•비정형 데이터를 개방형 파일로 저비용 저장하는 아키텍처이다.
- **데이터 웨어하우스**: 정형 BI를 위해 저장•질의•테이블 관리를 통합한 데이터 시스템이다.
- **데이터베이스 관리 시스템(Database Management System, DBMS)**: 데이터의 저장•조회•무결성•동시성을 관리하는 소프트웨어이다.

</details>

BI•SQL•ML•DBMS의 저장•질의 특성을 비교한다.

| 판단 기준 | 데이터 레이크 | 데이터 웨어하우스 | 데이터 레이크하우스 |
|:---|:---|:---|:---|
| 적용 기준 | **원시•비정형 데이터** 대량 저장 | 정형 BI와 **고성능 SQL** | BI•스트리밍•ML의 **테이블 통합** |
| 핵심 특징 | **개방형 파일•저비용 저장** | DBMS의 저장과 **테이블 통합 관리** | 파일 위의 **테이블 메타데이터** |
| 한계 | **트랜잭션•품질 관리** 곤란 | 저장•엔진 종속과 **복제 비용** | **파일 병합•통계 관리** 필요 |

#### 한줄 요약

- 원시 저장은 레이크, 정형 분석은 웨어하우스, 통합은 레이크하우스가 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **작은 파일 문제**: 다수의 소형 데이터 파일이 메타데이터 처리와 질의 입출력 비용을 높이는 현상이다.
- **스키마 계약**: 여러 엔진이 같은 테이블의 필드•자료형•변경 규칙을 일관되게 따르도록 정한 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **엔진 호환성** 미검증 시 기능•포맷 버전의 **지원 편차** | 읽기•쓰기 기능의 **상호운용 시험** | 다중 엔진 **포맷 호환성** 확보 |
| **파일 구조** 미검증 시 작은 파일•파티션의 **질의 성능 저하** | 병합•파일 재배치•**통계 최적화** | **질의 지연•비용** 감소 |
| **거버넌스** 미검증 시 다중 엔진의 **권한•스키마 불일치** | 중앙 카탈로그•정책•**스키마 계약** | **권한•스키마 일관성** 확보 |

#### 한줄 요약

- 다중 엔진의 기능 호환성을 검증하고 파일•통계 최적화와 중앙 정책으로 동일 테이블의 품질을 유지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **BI•ML 통합**: 분석 보고와 기계학습 워크로드가 동일한 테이블 상태를 공유하는 운영 방식이다.
- **파일 유지관리**: 작은 파일 병합•재배치•통계 갱신으로 질의 성능과 비용을 관리하는 활동이다.

</details>

- **BI•ML 통합** 워크로드는 레이크하우스, 고정 정형 분석은 웨어하우스를 선택하고 파일 유지관리 병행이 핵심이다.

#### 한줄 요약

- 데이터 레이크하우스는 테이블 포맷과 카탈로그•파일 유지관리를 함께 운영해야 한다.
