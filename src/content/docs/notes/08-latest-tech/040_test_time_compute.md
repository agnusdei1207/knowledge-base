## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **테스트 시점 연산(Test-Time Compute)**: 요청 난도와 위험에 따라 생성•탐색•검증 자원을 조절하는 접근이다.
- **추론 예산(Inference Budget)**: 한 요청의 토큰•후보•도구 호출•시간 상한이다.

</details>

- 정의/개념: 추론 중 생성•탐색•검증 예산을 조절하는 **테스트 시점 연산**
- 배경/필요성: 기존의 AI 성능 향상이 모델 파라미터 크기와 사전학습 데이터셋을 무작정 늘리는 사전학습 연산(Pre-training Compute) 스케일링에만 의존하여 기하급수적인 GPU 비용 및 데이터 고갈 한계에 직면함은 물론, 단순 질의와 초고난도 복합 추론 질의에 동일한 고정 추론 연산을 소비하는 비효율이 발생함에 따라, 질의의 난이도와 비즈니스 위험도에 맞추어 추론 시점의 사고 토큰(Thinking Tokens) 생성, 다중 경로 탐색, 앙상블 투표 및 검증기(Verifier) 평가에 동적 컴퓨팅 자원을 투입하는 테스트 시점 연산(Test-Time Compute / Inference Scaling) 패러다임을 도입하여 **사전학습 비용을 늘리지 않고도 추론 단계에서 정확도를 비약적으로 향상시키는 새로운 스케일링 법칙(Inference-Time Scaling Law) 확립, 과업 난도별 동적 연산 예산(Dynamic Inference Budget) 배분, OpenAI o1/o3 및 DeepSeek-R1 등 최신 추론형 모델의 핵심 동작 기반 완성**을 달성할 필요

#### 한줄 요약
- **난도**와 **위험**에 따라 예산을 조절하면 학습 비용을 늘리지 않고 정확도를 사지만 그 대가를 요청마다 지연과 토큰으로 되갚으므로, 사전학습 확장과 달리 비용이 운영 단계에 남는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **품질 향상 포화**: 연산 자원을 추가 투입할 때 얻어지는 품질 이득이 점차 둔화되는 비선형 성능 특성이다.
- **동적 예산 배정**: 요청의 난도•불확실성•영향도에 따라 서로 다른 추론 예산을 할당하는 방식.
- **조기 종료(Early Stopping)**: 품질이 충분하거나 추가 이득이 작아지면 남은 연산을 중단하는 제어다.

</details>

![추론 예산 증가에 따른 품질 향상 포화 곡선](/study/diagrams/test-time-compute.svg)

> 파란 품질 곡선의 기울기가 예산 증가와 함께 완만해져 추가 연산의 이득이 줄어들며, 정규화한 개념 좌표이지 실측값은 아니다.

- **추론 예산 확장**: 토큰•후보•검증 횟수 확대
- **동적 예산 배정**: 난도•위험별 추론 자원 할당
- **조기 종료**: 품질 정체나 예산 한계에서 연산 중단
- **품질 향상 포화**: 추가 연산 이득 감소와 지연•비용 증가

#### 한줄 요약
- **품질 포화점•지연 SLO** 기반 예산 확대와 종료 결정

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **난도•위험 추정기**: 과업 복잡도•불확실성•오류 영향도를 평가하여 필요한 연산 수준을 정하는 구성요소다.
- **예산 제어기**: 요청별 토큰•시간•후보 수•도구 호출 상한을 정하고 집행하는 구성요소다.
- **추론•탐색기**: 배정된 예산 안에서 후보 풀이를 생성•분기•수정하는 구성요소다.
- **검증기(Verifier)**: 규칙•모델•실행 환경으로 후보 답의 품질과 안전성을 판정하는 장치다.
- **종료•관측기**: 품질 통과•개선 정체•예산 초과를 판정하고 실행 결과를 기록한다.

</details>

```text
[난도•위험 추정기]──[예산 제어기]──[추론•탐색기]
                                          │
                                  [검증•정렬기]
                                          │
                                  [종료•관측기]
```

선의 의미: 난도•예산•탐색•검증•종료 책임의 정적 연결을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 난도•위험 추정기 | 복잡도•불확실성•**영향도** 산정 |
| 예산 제어기 | 토큰•후보•시간•**비용 상한** 할당 |
| 추론•탐색기 | 전략별 **복수 후보** 생성 |
| 검증•정렬기 | 품질•안전 기준으로 **후보 평가** |
| 종료•관측기 | 통과•정체•초과 판정과 **결과 기록** |

#### 한줄 요약
- **난도•예산•탐색•검증•종료** 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **예산 등급**: 난도와 위험별 토큰•시간•후보•도구 호출 상한 정책이다.
- **정책 환류**: 실제 품질•비용•지연 기록을 이용해 다음 요청의 예산 배정 기준을 보정하는 과정이다.

</details>

```text
요청•예산 제어기
       │ 1. 난도•위험 추정
       │ 2. 추론 예산 할당
       ▼
┌──── 품질 통과•예산 소진 전 반복 ────┐
│ 추론기                                │
│   │ 3. 후보 생성•탐색                 │
│   ▼                                   │
│ 검증기                                │
│   │ 4. 품질•안전 검증                 │
│   └── 검증 결과 반환 ──▶ 추론기       │
└───────────────────────────────────────┘
       │
       ▼
관측기
       │ 5. 종료•정책 환류
       │ 예산 정책 보정값 전달
       ▼
요청•예산 제어기
```

### 동작 원리

1. **난도•위험 추정**: 복잡도•불확실성•영향도 산정
2. **추론 예산 할당**: 토큰•시간•후보 상한 설정
3. **후보 생성•탐색**: 과업별 추론 전략 선택
4. **품질•안전 검증**: 임계값•제약으로 후보 판정
5. **종료•정책 환류**: 실행 기록으로 예산 보정

#### 한줄 요약
- **예산 할당•후보 검증•종료•정책 환류** 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **학습 시점 연산**: 모델 가중치에 반복 능력을 내재화하도록 학습 과정에 연산을 투자한다.
</details>

| 연산 확장 시점 | 학습 시점 연산 | 테스트 시점 연산 |
|:---|:---|:---|
| 적용 기준 | 반복 능력 **내재화** | 요청별 **가변 난도** 대응 |
| 핵심 특징 | 가중치 학습에 **연산 투자** | 생성•탐색•**검증 투자** |
| 한계 | 재학습 비용•주기 | 요청 지연•비용•**처리량 감소** |

#### 한줄 요약
- 능력 내재화는 **학습 시점**, 요청별 조절은 **테스트 시점**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **서비스 수준 목표(Service Level Objective, SLO)**: 지연•가용성•처리량처럼 서비스가 달성해야 할 운영 목표다.
- **95백분위 지연(95th Percentile Latency, P95 Latency)**: 전체 요청의 95%가 이 값 이하에서 완료되는 꼬리 지연 경계다.
- **처리량(Throughput)**: 시스템이 단위 시간에 처리할 수 있는 요청 수다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 난도 오판 | 불확실성•영향도 기반 **예산 등급화** | 고난도 **예산 부족 완화** |
| 품질 개선 정체 | 품질 증가 둔화 시 **조기 종료** | **불필요 연산 절감** |
| 꼬리 지연 증가 | **P95 지연•SLO•시간 상한** 적용 | **전체 처리량 보호** |
| 검증기 오류 | 규칙•환경 실행 기반 **교차 확인** | 고비용 **오답 선택 방지** |

#### 한줄 요약
- **예산 등급•조기 종료•P95 SLO** 기반 비용 통제

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 기반 예산 배정**: 오류 영향과 불확실성이 큰 문제에만 추가 추론•검증 자원을 집중하는 방식이다.
- **품질 포화 조기 종료**: 추가 품질 이득이 둔화되거나 P95 지연 SLO에 도달하면 추론을 멈추는 제어로 정의된다.

</details>

- 사전학습 중심의 전통적 스케일링 한계를 돌파하고 모델의 문제 해결 역량을 추론 시점에 동적으로 증폭시키는 **차세대 인공지능의 핵심 패러다임이자 최신 추론 모델 경쟁의 중심축(Test-Time Compute / Inference-Time Scaling Laws / Long CoT & Thinking Tokens / Search & Verifiers: PRM / Dynamic Budgeting & P95 SLO)의 절대적 표준 기술**로 확고히 자리 잡았으며, 강화학습 기반의 내부 사고 토큰 확장과 능동적 검증 체계로 급속히 발전하는 가운데, 실무 엔터프라이즈 시스템 적용 시에는 **과업 복잡도 및 비즈니스 영향도를 사전에 분류하여 차등적 추론 예산(Budget Tiers)을 할당하는 지능형 라우팅 구현, 추가 연산 투입 대비 성능 향상이 둔화되는 포화 지점에서의 조기 종료(Early Stopping) 정책 적용, 꼬리 지연(P95/P99) 폭증을 방지하기 위한 엄격한 서비스 수준 목표(SLO) 및 타임아웃 통제**를 결합하여 완벽한 추론 지능과 운영 비용 경제성을 완성

#### 한줄 요약
- **품질 포화점•P95 SLO** 기반 추론 예산 확대와 종료 결정
