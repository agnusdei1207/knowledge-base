## 미리 알고가기

- **거대 언어 모델(Large Language Model, LLM)**: 영문 머리글자를 딴 표기로 “엘엘엠”으로 읽으며, 토큰 분포로 언어 과업을 수행하는 모델
- **테스트 시점 연산(Test-Time Compute)**: 추론 시 생성·탐색·검증 예산 증대
- **추론 스케일링(Inference Scaling)**: 추론 연산량에 따른 품질 변화 분석
- **예산 제어기(Budget Controller)**: 요청별 토큰·시간·비용 상한 배정
- **검증기(Verifier)**: 규칙·모델·환경으로 후보 답 평가
- **사고 사슬(CoT)**: 하나의 중간 단계 경로로 답 생성
- **사고 트리(ToT)**: 여러 중간 상태를 분기·평가해 탐색
- **자기 일관성(Self-Consistency)**: 여러 추론 경로의 최빈 답 선택
- **SLO(Service Level Objective)**: 지연·가용성의 운영 목표 정의
- **P95(95th Percentile)**: 요청 95%가 포함되는 지연 경계



## Ⅰ. 개요

- 정의/개념: 추론 중 탐색·검증 연산을 늘리는 접근
- **배경/필요성**: 고정 추론 예산만으로 문제 난도별 품질·지연·비용 균형 조정 곤란

### 쉽게 이해하기 (학습용)
- 쉬운 문제는 바로 풀고 어려운 문제는 여러 풀이와 검산에 더 많은 시간 투자

## Ⅱ. 특징

- 토큰·후보·검증 횟수 기반 **추론 예산 확대**
- 난도·위험별 예산 배정과 **조기 종료**
- 품질 한계효용과 **지연·비용·처리량** 상충

### 쉽게 이해하기 (학습용)
- 오래 생각해도 잘못된 방향을 반복하면 품질 저하 우려

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
|:---|:---|
| 난도 추정기 | 복잡도·불확실성·영향 추정 |
| 예산 제어기 | 토큰·후보·시간·비용 상한 배정 |
| 추론·탐색기 | CoT·ToT·도구로 후보 생성 |
| 검증·정렬기 | 규칙·모델·환경으로 후보 평가 |
| 종료·관측 | 통과·정체·초과 판정 및 기록 |

```text
테스트 시점 연산
├─ 난도 추정기
├─ 예산 제어기
├─ 추론·탐색기
├─ 검증·정렬기
└─ 종료·관측
```

### 쉽게 이해하기 (학습용)

- 문제마다 사용할 시간과 도구 수를 정하고 검증된 답이 나오면 남은 예산을 쓰지 않고 멈춤

## Ⅳ. 원리 및 절차 흐름도

```text
난도추정
  ↓
예산할당
  ↓
후보생성
  ↓
결과검증
  ↓
종료환류
```

| 절차 | 설명 |
|:---|:---|
| 절차 | 설명 |
|:---|:---|
| 난도추정 | 복잡도·불확실성·영향 추정 |
| 예산할당 | 토큰·후보·도구·시간 상한 정함 |
| 후보생성 | 선택 전략으로 복수 후보 생성 |
| 결과검증 | 품질·안전성 평가 |
| 종료환류 | 결과 기록해 정책 보정 |

### 쉽게 이해하기 (학습용)

- 충분히 검증된 답은 일찍 끝내고 계속 불확실하면 무한 계산 대신 사람에게 넘김

## Ⅴ. 모델 연산 확장 시점 비교

| 구분 | 학습 시점 연산 | 테스트 시점 연산 |
|:---|:---|:---|
| 투입 시점 | 모델 학습 단계 | 개별 요청 추론 단계 |
| 주요 수단 | 데이터·매개변수·학습 | 토큰·후보·탐색·검증 |
| 적용 기준 | 반복 능력 내재화 | 문제별 가변 난도 대응 |
| 핵심 특징 | 가중치 학습에 연산 투자 | 추론 탐색·검증에 연산 투자 |
| 한계 | 재학습 비용·주기 | 요청 지연·비용 증가 |

> 요약: 추론 시점의 동적 자원 배분으로 품질 제고

### 쉽게 이해하기 (학습용)

- 미리 더 많이 공부시키는 방식과 실제 검증 문제마다 풀이 시간을 다르게 쓰는 방식의 차이임

## Ⅵ. 실무 사례

- 코드 난도에 따라 후보·테스트 예산을 선택한다
- 정확도·한계효용·p95 지연·비용을 측정한다

### 쉽게 이해하기 (학습용)

- 일부 어려운 문제의 품질을 올리려다 전체 사용자의 지연과 비용이 과도해지지 않는지 봐야 함

## Ⅶ. 결론

- 추론 시 생성·탐색·검증 자원을 조절한다
- 적응형 예산·검증·조기 종료로 비용을 맞춘다

### 쉽게 이해하기 (학습용)

- 더 많은 계산보다 필요한 문제에만 검산 예산을 쓰고 멈출 기준을 두는 설계가 중요함
