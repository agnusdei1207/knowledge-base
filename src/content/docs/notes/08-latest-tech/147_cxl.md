## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴퓨트 익스프레스 링크(Compute Express Link, CXL)**: PCIe 물리 계층에서 입출력과 캐시•메모리 일관성을 제공하는 연결 표준이다.
- **주변장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe)**: CXL이 공유하는 물리•전기 연결 기반이다.

</details>

- 정의: **PCIe 물리 계층**에서 캐시•메모리 일관성을 제공하는 CXL
- 배경/필요성: 데이터센터의 AI 모델 규모와 인메모리 데이터베이스(DB) 용량이 기하급수적으로 폭증하는 반면, 기존 CPU 메인보드의 DDR 메모리 채널 확장성은 물리적 핀 수와 폼팩터 한계에 도달하고, 기존 PCIe 버스는 CPU와 가속기/메모리 장치 간 하드웨어 캐시 일관성(Cache Coherency)을 지원하지 않아 데이터 접근 시마다 OS 드라이버를 거치는 무거운 DMA 복사 오버헤드와 메모리 단편화(Stranded Memory)에 직면함에 따라, PCIe 5.0/6.0 물리 계층 위에서 초저지연 캐시 일관성과 메모리 의미론(Memory Semantics)을 제공하는 개방형 산업 표준 인터커넥트인 CXL(Compute Express Link: CXL 2.0/3.1 / CXL.io, CXL.cache, CXL.mem, Type-1/2/3 Devices, Memory Pooling & Sharing, Direct Memory Access without OS Overhead) 아키텍처를 도입하여 **호스트 CPU와 가속기 간 하드웨어 수준의 양방향 캐시 일관성(CXL.cache) 확보, 별도의 메모리 컨트롤러를 장착한 Type-3 CXL 메모리 확장을 통한 서버당 수십 테라바이트급 메모리 용량 및 대역폭 확장, 다중 호스트 서버가 단일 메모리 풀을 동적으로 공유하고 분배하는 메모리 풀링(Memory Pooling)을 통한 TCO 절감**을 달성할 필요

#### 한줄 요약

- 장치 역할별 **입출력•캐시•메모리 프로토콜** 제공

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CXL.io**: 장치 발견•설정•입출력과 오류 관리를 제공하는 PCIe 호환 프로토콜이다.
- **CXL.cache**: 장치가 호스트 메모리를 일관되게 캐시하도록 지원하는 프로토콜이다.
- **CXL.mem**: 호스트가 장치 메모리에 일관되게 접근하도록 지원하는 프로토콜이다.

</details>

**CXL**의 입출력•호스트 캐시•장치 메모리용 프로토콜 조합

- CXL.io 기반 **장치 발견•설정•입출력**
- CXL.cache 기반 **호스트 메모리 캐시 일관성**
- CXL.mem 기반 **장치 메모리 일관 접근**

#### 한줄 요약

- 공통 입출력 위에 **캐시•메모리 일관성** 선택 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **호스트 브리지**: 프로세서의 메모리 체계와 CXL 장치 사이에서 주소•일관성 경계를 제공하는 구성요소이다.
- **CXL 메모리 장치**: CXL.mem으로 호스트 주소 공간에 용량•대역폭을 제공하는 장치이다.
- **스위치 관리 계층**: 여러 CXL 장치의 연결 경로•자원•오류 상태를 관리하는 계층이다.

</details>

**CXL 링크**로 호스트 브리지와 가속기•메모리 장치 연결

```text
[CXL 아키텍처]
├── [호스트 브리지]
│   ├── 일관성 경계 제어
│   └── 주소 범위 매핑
├── [CXL 링크 프로토콜]
│   ├── CXL.io (입출력/발견)
│   ├── CXL.cache (캐시 일관성)
│   └── CXL.mem (메모리 접근)
└── [연결 장치 및 관리]
    ├── [가속기 장치]
    ├── [메모리 장치]
    └── [스위치 관리 계층]
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 호스트 브리지 | **장치 발견•일관성 기준** 경계 |
| CXL 링크 | **CXL.io•cache•mem** 전송 경로 |
| 가속기 장치 | **캐시•장치 메모리 연산** 제공 |
| 메모리 장치 | **CXL.mem 확장 자원** 제공 |
| 스위치 관리 계층 | **경로•자원•오류 처리** 관리 |

#### 한줄 요약

- 호스트 발견과 **유형별 캐시•메모리 경로•오류 격리** 구조

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **링크 훈련**: 양 끝 장치가 물리 연결 속도•폭•동작 모드를 협상해 통신 경로를 여는 과정이다.
- **주소 범위 구성**: 호스트 주소 공간의 일부를 CXL 장치 메모리에 매핑하는 절차이다.

</details>

```text
호스트 브리지
   │ 1. 링크 훈련•CXL 모드
   ▼
CXL 링크
   │ 2. CXL.io 발견•기능 정보
   ▼
가속기•메모리 장치
   └── 3. cache•mem 프로토콜 능력 ──▶ 호스트 브리지
호스트 브리지 ── 4. 주소 범위•경로 구성 ──▶ 스위치 관리 계층
호스트 브리지 ◀── 일관 접근•오류 상태 ───── 스위치 관리 계층
```

### 동작 원리

1. 링크 훈련•CXL 모드: **PCIe 물리 경로**와 동작 모드 협상
2. CXL.io 발견•기능 정보: 장치 식별자•오류 능력 확인
3. cache•mem 프로토콜 능력: 장치 유형별 지원 조합 판정
4. 주소 범위•경로 구성: 호스트 주소 공간과 장치 메모리 연결

#### 한줄 요약

- 링크•장치 유형 확인 후 **주소 범위•일관 경로** 구성

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Type-1 장치**: CXL.io와 CXL.cache로 호스트 메모리를 캐시하는 가속기이다.
- **Type-2 장치**: CXL.io•CXL.cache•CXL.mem으로 호스트와 장치 메모리를 함께 사용하는 가속기이다.
- **Type-3 장치**: CXL.io와 CXL.mem으로 메모리 용량•대역폭을 확장하는 장치이다.

</details>

**CXL Type-1•2•3 장치**의 캐시•메모리 프로토콜 조합 비교

| CXL 장치 유형 | Type-1 장치 | Type-2 장치 | Type-3 장치 |
|:---|:---|:---|:---|
| 적용 기준 | **호스트 메모리 캐시 가속** | **장치 메모리 보유 가속** | **메모리 용량•대역폭 확장** |
| 핵심 특징 | **CXL.io•cache** | **CXL.io•cache•mem** | **CXL.io•mem** |
| 한계 | **장치 메모리 없음** | **일관성•주소 관리 복잡** | **로컬 메모리보다 높은 지연** |

> 요약: **Type-1•2**는 가속기, **Type-3**은 메모리 확장 중심

#### 한줄 요약

- 호스트 캐시는 Type-1, 양방향 메모리는 Type-2, **확장은 Type-3**

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **메모리 계층 배치**: 접근 빈도와 지연 요구에 따라 데이터를 로컬•확장 메모리에 나누어 두는 방법이다.
- **오류 격리**: 한 주소 범위나 장치의 장애가 다른 공유 자원으로 퍼지지 않게 차단하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장치 유형•**프로토콜 불일치** | Type별 **CXL.io•cache•mem 조합** 검증 | **미지원 경로** 구성 방지 |
| 원격 메모리 **지연 증가** | 접근 빈도별 **메모리 계층 배치** | **로컬•확장 메모리** 균형 |
| 공유 주소 **오류 확산** | 범위별 **오류 격리•복구** 설계 | **일관성 장애** 확산 제한 |

#### 한줄 요약

- 프로토콜 조합•메모리 계층•**오류 격리**를 함께 검증

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **캐시 일관성**: 여러 처리기와 장치의 캐시가 같은 메모리 위치에 대해 모순 없는 값을 유지하는 성질이다.
- **메모리 확장**: 컴퓨트 익스프레스 링크 장치를 호스트 주소 공간에 연결해 사용 가능한 용량과 대역폭을 늘리는 방식이다.

</details>

- 서버 내부의 폐쇄적 메모리 아키텍처를 랙/클러스터 수준의 유연한 분합형(Disaggregated) 메모리 풀로 혁신하는 **차세대 데이터센터 및 하이퍼스케일러 인프라의 최고 핵심 인터커넥트 표준(Compute Express Link: CXL 3.1 / PCIe 5.0/6.0 Physical Layer / CXL.io, CXL.cache, CXL.mem Multi-protocols / Type-1,2,3 Devices / Memory Pooling & Dynamic Fabric Sharing / Stranded Memory Zeroization)의 확고한 표준**으로 확고히 자리 잡았으며, CXL 스위치 기반의 컴포저블 인프라(Composable Infrastructure) 및 CXL-PIM 연산 융합으로 발전하는 가운데, 실무 CXL 시스템 구축 시에는 **가속기 연산에는 Type-2를, 인메모리 DB 및 LLM 파라미터 용량 확장에는 Type-3 CXL.mem 장치를 배치하고, NUMA 계층 인지 소프트웨어(Tiered Memory Management)를 적용하여 핫 데이터는 로컬 DDR에, 웜/콜드 데이터는 CXL 풀에 자동 계층화**를 결합하여 완벽한 메모리 활용률과 대규모 분산 컴퓨팅 효율을 완성

#### 한줄 요약

- 장치 유형별 프로토콜과 **주소•일관성•오류 격리** 설계
