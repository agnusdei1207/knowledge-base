## 미리 알고가기

- **사고 사슬(Chain-of-Thought, CoT)**: 긴 계산을 중간 식으로 나누어 검산하듯 복합 문제의 중간 추론 단계를 순서대로 생성하는 방식
- **순차 추론(Sequential Reasoning)**: 앞 단계의 부분 결과를 다음 단계의 입력으로 이어 답을 도출하는 과정
- **자기 일관성(Self-Consistency)**: 여러 추론 경로에서 반복해 나온 답을 선택하는 기법
- **검증기(Verifier)**: 규칙·계산기·검색 결과로 생성된 후보 답의 타당성을 별도로 확인하는 장치
- **비충실성(Unfaithfulness)**: 모델이 생성한 설명이 실제 답을 선택한 내부 근거와 일치한다고 보장할 수 없는 성질
- **토큰(Token)**: 모델이 입력과 출력을 처리할 때 사용하는 문자·단어 조각 단위
- **조기 종료(Early Stopping)**: 충분한 품질을 얻거나 예산 한계에 도달하면 추가 추론을 멈추는 제어

## Ⅰ. 개요

- 정의/개념: 복합 문제의 **중간 추론 단계**를 생성해 답을 도출하는 기법
- 배경/필요성: 직접 응답의 **다단계 조건 누락·중간 오류** 확인 필요

### 쉽게 이해하기 (학습용)

- 어려운 계산의 답만 적지 않고 중간 식을 차례로 남기면 어느 단계에서 조건이나 계산이 틀렸는지 확인할 수 있음

## Ⅱ. 특징

- 부분 문제를 잇는 **순차 추론**으로 복합 조건 분해
- 다중 경로·검증기를 결합한 **자기 일관성·오류 보정**
- 생성 설명과 실제 판단 근거가 다를 수 있는 **비충실성**

### 쉽게 이해하기 (학습용)

- 풀이 노트가 길어도 실제로 답을 고른 근거와 다를 수 있으므로, 중간 단계를 읽는 것과 정답을 검산하는 일을 구분해야 함

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 3
  input["과업·조건 입력"]
  reasoner["추론 생성기"]
  extractor["답 추출기"]
  verifier["검증기"]
  boundary["응답 경계"]
  input --- reasoner
  reasoner --- extractor
  extractor --- verifier
  verifier --- boundary
```

| 구성요소 | 책임 |
|:---|:---|
| **과업·조건 입력** | 목표·제약·**성공 기준** 제공 |
| **추론 생성기** | 순서화된 **중간 단계** 생성 |
| **답 추출기** | 추론에서 **최종 후보** 분리 |
| **검증기** | 규칙·계산·검색 기반 **후보 확인** |
| **응답 경계** | 검증된 **결론·근거**만 노출 |

### 쉽게 이해하기 (학습용)

- 문제지가 조건을 주고 풀이자가 중간 식을 만든 뒤 답만 골라 검산기에 넘기며, 응답 경계는 확인된 결론과 근거만 밖으로 내보냄

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
  participant U as 사용자
  participant R as 추론 모델
  participant E as 답 추출기
  participant V as 검증기
  U->>R: 1. 문제·조건 정리
  R->>E: 2. 중간 추론 생성
  E->>V: 3. 최종 후보 추출
  V-->>R: 4. 규칙·도구 검증
  V-->>U: 5. 결론·근거 제시
```

1. **문제·조건 정리**: 목표·제약 명시로 **조건 누락** 방지
2. **중간 추론 생성**: 부분 결과를 잇는 **단계 경로** 구성
3. **최종 후보 추출**: 추론 설명과 **답 후보** 분리
4. **규칙·도구 검증**: 계산·검색 기반 **독립 교차 확인**
5. **결론·근거 제시**: 민감한 추론 대신 **검증 근거** 제공

### 쉽게 이해하기 (학습용)

- 문제 조건을 적고 중간 풀이를 만든 다음 답 후보만 떼어 계산기나 자료로 검산해 확인된 결론을 제시하는 순서임

## Ⅴ. 종류 및 비교

| 응답 방식 | 직접 응답 | 사고 사슬 |
|:---|:---|:---|
| 적용 기준 | **단순·저위험 과업** | **다단계·검증 가능 과업** |
| 핵심 특징 | 중간 단계 없이 **답 생성** | **중간 추론** 후 답 추출 |
| 한계 | **복합 조건 누락** | 토큰 비용·**비충실성** |

### 쉽게 이해하기 (학습용)

- 단순 질문은 바로 답하는 편이 효율적이고 여러 조건을 잇는 문제는 중간 풀이와 검산을 두는 편이 오류를 찾기 쉬움

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 그럴듯한 중간 오류 | 계산기·규칙·검색 기반 **독립 검증** | **오답 전파** 감소 |
| 민감정보 노출 | 결론과 **검증 근거**만 공개 | **정보 노출** 축소 |
| 토큰·지연 증가 | 난도별 예산·**조기 종료** 적용 | **응답 비용** 통제 |
| 경로 편향 | 다중 경로·**자기 일관성** 비교 | 단일 경로 의존 완화 |

### 쉽게 이해하기 (학습용)

- 풀이를 길게 쓰게 하기보다 계산기로 검산하고 필요한 근거만 공개하며, 쉬운 문제는 일찍 멈춰 시간과 비용을 아껴야 함

## Ⅶ. 결론

- **과업 난도·검증 가능성**으로 CoT 적용 여부를 정하고 **외부 검증**으로 생성 설명의 비충실성 통제

### 쉽게 이해하기 (학습용)

- 복잡하고 검산 가능한 문제에만 중간 풀이를 사용하고, 풀이의 말솜씨가 아니라 별도 검사 결과로 답을 믿어야 함
