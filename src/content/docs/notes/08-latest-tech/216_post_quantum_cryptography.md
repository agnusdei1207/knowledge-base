## 미리 알고가기

- **PQC(Post-Quantum Cryptography)**: 양자컴퓨터 공격에도 안전하게 설계된 공개키 암호
- **전환 배경**: RSA·ECC가 쇼어 알고리즘에 취약하여 선제적 migration이 필요함
- **KEM(Key Encapsulation Mechanism)**: 암호키 전달 방식과 전자서명 중심의 하이브리드 전략이 중요함



## Ⅰ. 개요

- **정의/개념**: 양자 공격을 견디는 공개키 암호 체계
- **배경/필요성**: RSA·ECC 붕괴와 장기 기밀 선취 위협에 대응

### 쉽게 이해하기 (학습용)

- 양자용 새 암호로 기존 시스템의 공개키 방식을 교체함

## Ⅱ. 특징

- KEM·서명 분리가 용도별 알고리즘을 선택하게 한다.
- 표준 매개변수가 보안강도·성능을 구분한다.
- HNDL이 장기 기밀 자산의 선제 전환을 재촉한다.
- 암호 민첩성이 호환성·교체 위험을 줄인다.

### 쉽게 이해하기 (학습용)

- 시스템 전체의 호환성과 배포 절차까지 함께 검증해야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| Crypto Inventory | 암호 자산·라이브러리·HSM 위치 및 위험 식별 |
| Algorithm Profile | 표준 알고리즘과 용도별 파라미터 선택 |
| Hybrid 운영 | 기존 암호와 병행 및 downgrade 방지 구성 |
| Governance | 상호운용성, 성능 및 수명 주기 관리 |

  └─ 암호 자산·알고리즘·하이브리드·거버넌스

> 요약: 암호 자산 식별 후 하이브리드로 점진 전환

### 쉽게 이해하기 (학습용)

- 중요 자료부터 새 자물쇠를 맞추고 단계적으로 교체함

## Ⅳ. 원리 및 절차 흐름도

```text
자산식별
  ↓
우선순위
  ↓
알고선택
  ↓
하이브리드
  ↓
폐기완료
```

| 절차 | 설명 |
|:---|:---|
| 자산식별 | 암호 자산·HSM·통신 목록화함 |
| 우선순위 | 데이터 수명·위험성 기반 정함 |
| 알고선택 | 표준 알고리즘과 환경 적합성 판단함 |
| 하이브리드 | 기존 암호 병행 및 상호운용 검증함 |
| 폐기완료 | 단계 배포 및 legacy 제거 수행함 |

> 요약: 위험 자산부터 검증 후 기존 암호 제거

### 쉽게 이해하기 (학습용)

- 중요 보안 자산부터 문제없는 것을 확인하고 옛 방식 폐기함

## Ⅴ. 종류 및 비교

| 판단 기준 | Classical PK | PQC | QKD |
|:---|:---|:---|:---|
| 핵심 특징 | 수학적 난제 기반 | 양자내성 난제 기반 | 양자 측정 원리 |
| 적용 기준 | key, 서명 제공 | key, 서명 제공 | 키 분배, 감지 |
| 주요 위험 | 기존 서버 기반 | 기존 인프라 활용 | 전용 광장비 필요 |

> 요약: PQC와 QKD의 목적·운영 환경 구분

### 쉽게 이해하기 (학습용)

- PQC는 수학 알고리즘 교체, QKD는 전용 통신 장비 도입임

## Ⅵ. 실무 사례

1. 대상 환경의 도입 조건과 설계를 검증함
2. 운영 위험과 성과 지표를 검증함

### 쉽게 이해하기 (학습용)

- 금융 TLS 전환: gateway·서버의 기존 암호를 표준 PQC로 검증하여 단계적 배포함
- 펌웨어 서명: 중요 장비의 서명 체계를 PQC 기반으로 교체하고 trust 갱신함

## Ⅶ. 결론

- 자산 수명·호환성으로 PQC 전환 순서와 방식 결정

### 쉽게 이해하기 (학습용)
