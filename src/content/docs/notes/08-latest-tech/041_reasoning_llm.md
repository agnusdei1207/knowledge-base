## 미리 알고가기

- **대규모 언어모델(Large Language Model, LLM, 엘엘엠)**: 영문 머리글자를 딴 언어 모델로, 언어·코드 패턴을 학습
- **강화학습(Reinforcement Learning, RL, 알엘)**: 영문 머리글자를 딴 학습법으로, 보상에 따라 행동 정책을 개선
- **검증가능 보상 강화학습(Reinforcement Learning with Verifiable Rewards, RLVR, 알엘브이알)**: 정답·실행 결과처럼 자동 검증 가능한 보상으로 추론 정책을 학습
- **지도 미세조정(Supervised Fine-Tuning, SFT)**: 풀이 예시로 응답 형식을 조정함
- **시험 시점 연산(Test-Time Compute, TTC)**: 요청별 추론 자원을 추가 배정함
- **핵심 판단**: 긴 답변보다 검증 가능한 추론 결과를 중시함



## Ⅰ. 개요

- 정의/개념: 다단계 해결·검증에 특화된 언어 모델
- 기존 한계: 즉시 생성 중심 LLM은 다단계 검증 과업에 취약
- **배경/필요성**: 복합 문제의 해결·도구 사용·결과 검증 강화

### 쉽게 이해하기 (학습용)

- 문제를 나누고 계산·도구·검증에 시간을 쓰도록 학습된 모델

## Ⅱ. 특징

- 후학습으로 다단계 문제 해결 정책을 강화한다
- 요청 난도에 따라 시험 시점 연산 예산을 조절한다
- 정답·코드 실행·도구 결과로 최종 출력을 검증한다

### 쉽게 이해하기 (학습용)

- 모든 질문을 오래 생각하는 것은 비효율적임

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 기반 모델 | 언어·코드·지식 사전학습 |
| 추론 후학습 | SFT·RL·검증 보상 정책 조정 |
| Budget Controller | 토큰·시간·도구 예산 관리 |
| Verifier·도구 | 계산·실행·검색 규칙 검증 |
| 응답·안전 계층 | 답·근거·권한 감사 연결 |

> 요약: 예산·도구·검증기가 추론 결과를 통제함

### 쉽게 이해하기 (학습용)

- 문제 난도를 보고 풀이 시간과 도구를 정한 뒤 검증을 통과한 결과만 응답함

## Ⅳ. 원리 및 절차 흐름도

```text
분류
↓
예산
↓
추론
↓
검증
↓
환류
```

| 절차 | 설명 |
|:---|:---|
| 분류 | 난도별 일반·추론 경로 선택함 |
| 예산 | 토큰·시간·도구 상한 배정함 |
| 추론 | 후보 생성 및 도구 실행함 |
| 검증 | 규칙·실행·안전 기준 확인함 |
| 환류 | 한계효용 평가 후 정책 갱신함 |

> 요약: 난도별 예산으로 추론하고 검증 결과를 환류함

### 쉽게 이해하기 (학습용)

- 품질 이득이 비용보다 클 때만 추론 경로 사용함

## Ⅴ. 종류 및 비교

| 판단 기준 | 일반 대화 LLM | 추론 특화 LLM |
|:---|:---|:---|
| 적용 기준 | 단순·지연 민감 응답 | 복합·검증 가능 과업 |
| 핵심 특징 | 즉시 생성·지시 이행 | 다단계 해결·검증 |
| 한계 | 복합 추론 오류 | 높은 지연·연산 비용 |

> 요약: 단순 응답은 일반, 복합 검증은 추론 모델 사용함

### 쉽게 이해하기 (학습용)

- 빠른 상담원과 복잡한 사건에 시간을 더 쓰는 분석가의 역할 차이와 비슷함

## Ⅵ. 실무 사례

- 코드 수정은 저장소·분석·샌드박스 연결 및 결과 검증함
- 벤치마크는 오염·도구·반복 횟수를 반드시 확인해야 함

### 쉽게 이해하기 (학습용)

- 검증 문제 성적이 높아도 실제 회사 코드와 도구에서 같은 성능이 나오는지는 별도 확인해야 함

## Ⅶ. 결론

- 추론 특화 LLM은 후학습과 가변 자원으로 복합 문제 해결 강화
- 정확도·근거·비용을 평가해 모델 조합 최적화 필요

### 쉽게 이해하기 (학습용)

- 오래 생각하는 모델보다 필요한 문제에 검증 자원을 알맞게 쓰는 모델이 실무에 유용함
