## 미리 알고가기

- **토큰당 출력 지연(Time per Output Token, TPOT)**: 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 시간
- **최초 토큰 지연(Time to First Token, TTFT)**: 요청부터 첫 출력 토큰을 받을 때까지의 초기 지연
- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 키·값 벡터를 저장하여 다음 토큰 생성에 재사용하는 메모리
- **키-값 헤드(KV Head)**: 어텐션에서 키·값 벡터를 생성하며 여러 쿼리 헤드가 공유할 수 있는 연산 단위
- **동적 배치(Dynamic Batching)**: 실행 중인 요청을 도착 시점과 상태에 따라 배치에 추가·제거하는 방식
- **메모리 대역폭(Memory Bandwidth)**: 일정 시간 동안 메모리와 연산 장치 사이에서 전송할 수 있는 데이터 양
- **로짓(Logit)**: 다음 토큰 후보마다 모델이 계산한 정규화 전 점수
- **샘플러(Sampler)**: 로짓 분포와 생성 설정을 바탕으로 다음 토큰을 선택하는 구성요소

## Ⅰ. 개요

- 정의/개념: **TPOT**는 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 지연
- 배경/필요성: TTFT만으로는 스트리밍 시작 후 **디코드 지속 속도**의 평가 곤란

### 쉽게 이해하기 (학습용)
- 답이 시작된 뒤 다음 토큰들이 얼마나 빠르게 이어지는지 나타냄

## Ⅱ. 특징

- `TPOT = (마지막 토큰 수신 시각 - 첫 토큰 수신 시각) / (출력 토큰 수 - 1)`의 **평균 토큰 간 지연**
- 단일 연속 생성에서 `출력 속도 ≈ 1000 / TPOT(ms/token)`인 **지연·속도 역관계**
- KV 캐시 대역폭이 낮거나 배치·동시성이 크면 **디코드 지연 증가**

### 쉽게 이해하기 (학습용)
- TPOT가 작을수록 첫 답 뒤의 문장이 더 빠르게 이어짐

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
    columns 3
    S["디코드 스케줄러"]
    K["KV 캐시 관리자"]
    E["모델 엔진"]
    P["샘플러"]
    T["스트리머"]
    S --- K
    K --- E
    E --- P
    P --- T
```

| 구성요소 | 책임 |
|:---|:---|
| 디코드 스케줄러 | 활성 요청의 **동적 배치 편성** |
| KV 캐시 관리자 | 과거 키·값 조회와 **신규 값 추가** |
| 모델 엔진 | 다음 토큰 후보의 **로짓 계산** |
| 샘플러 | 로짓과 생성 설정에 따른 **다음 토큰 선택** |
| 스트리머 | 토큰 전송과 **수신 시각 기록** |

### 쉽게 이해하기 (학습용)
- 과거 계산을 읽어 다음 토큰을 고르고 전송한 뒤 새 계산값을 저장함

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant S as 스케줄러
    participant K as KV 캐시
    participant E as 모델 엔진
    participant P as 샘플러
    participant T as 스트리머
    S->>K: 1. 활성 요청 배치 편성
    K->>E: 2. 이전 키·값 조회
    E->>P: 3. 다음 토큰 로짓 계산
    P->>K: 4. 토큰 선택·신규 값 추가
    K-->>T: 5. 토큰 전송·간격 기록
```

1. **활성 요청 배치 편성**: 실행 가능한 요청을 묶어 **디코드 순서** 결정
2. **이전 키·값 조회**: 각 요청의 과거 문맥에 해당하는 **캐시 데이터** 전달
3. **다음 토큰 로짓 계산**: 모델 계층을 실행해 후보별 **생성 점수** 산출
4. **토큰 선택·신규 값 추가**: 다음 토큰을 확정하고 해당 토큰의 **키·값 캐시** 확장
5. **토큰 전송·간격 기록**: 수신 시각 차이로 **토큰 간 밀리초 지연** 측정

### 쉽게 이해하기 (학습용)
- 같은 과정을 토큰마다 반복하며 전송 간격을 기록함

## Ⅴ. 종류 및 비교

| 비교 기준 | TTFT | TPOT | 처리량 |
|:---|:---|:---|:---|
| 적용 기준 | 초기 반응성 관리 | 개별 스트리밍 속도 관리 | 서버 전체 자원 효율 관리 |
| 핵심 특징 | 첫 응답의 **초기 지연** | 출력 토큰당 **평균 생성 지연** | 단위 시간의 **전체 처리량** |
| 한계 | 지속 생성 속도 미반영 | 초기 대기·완료 시간 미반영 | 개별 사용자 지연 미반영 |

### 쉽게 이해하기 (학습용)
- 시작 속도와 한 요청의 이어쓰기 속도, 서버 전체 생산량은 서로 다른 목표임

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| KV 읽기의 **메모리 대역폭 병목** | 키·값 헤드 공유·저정밀 캐시·캐시 배치 최적화 | 토큰 간 지연 **절감** |
| 과대 동적 배치의 **개별 지연 증가** | 지연 목표별 배치 상한 설정 | 꼬리 지연 **완화** |
| 불규칙한 **토큰 간 정지** | 토큰별 시각과 p95 간격 계측 | 평균값의 병목 은폐 **방지** |

### 쉽게 이해하기 (학습용)
- 큰 배치의 서버 효율과 한 사용자의 토큰 간 지연을 함께 측정함

## Ⅶ. 결론

- p95 TPOT의 원인이 대역폭이면 **KV 공유·양자화**, 배치면 **동시 요청 상한** 적용

### 쉽게 이해하기 (학습용)
- 답이 이어지는 체감 속도와 서버 효율을 함께 맞춤
