## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **토큰당 출력 지연(Time per Output Token, TPOT)**: 첫 토큰 이후 출력 토큰 하나를 생성하는 평균 시간으로 정의된다.
- **디코드 지속 속도(Decode Sustained Speed)**: 첫 응답 이후 토큰이 연속해서 생성•전송되는 속도를 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **최초 토큰 지연(Time to First Token, TTFT)**: 요청부터 첫 출력 토큰까지의 초기 지연이다.

</details>

- 정의: 첫 토큰 이후 출력 토큰 하나의 평균 지연인 **TPOT**
- 배경/필요성: 대규모 언어 모델(LLM)의 스트리밍 서빙 환경에서 최초 응답 지연(TTFT)만을 최적화할 경우, 첫 토큰 출력 이후 이어지는 텍스트 생성 과정에서 동시 배치 수 증가 및 GPU VRAM 대역폭 포화로 인해 토큰 간 간격이 늘어지고 응답이 뚝뚝 끊기는(Stuttering) 체감 품질 저하를 사전에 감지하고 방어할 수 없는 결함이 발생함에 따라, 최초 토큰 수신 이후 전체 출력이 완료될 때까지 생성되는 토큰당 평균 소요 시간을 정밀 측정하는 토큰당 출력 지연(TPOT: Time per Output Token / Inter-Token Latency) 메트릭을 도입하여 **자기회귀(Autoregressive) 디코딩 단계의 순수 메모리 대역폭(Memory Bandwidth Bound) 병목 지속 관측, 인간의 자연스러운 읽기 속도(15~20+ Tokens/Sec)를 충족하는 디코딩 처리 속도 보장, KV Cache 압축(GQA/양자화) 및 연속 배치(Continuous Batching) 스케줄링의 튜닝 기준점 확립**을 달성할 필요

#### 한줄 요약
- **토큰당 평균 생성 지연**은 배치를 키울수록 나빠지고 TTFT와도 서로 당기므로, 두 지표를 함께 목표로 걸어야 처리량 최적화가 체감 품질을 갉아먹는 것을 막는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **키-값 캐시(Key-Value Cache, KV Cache)**: 이전 토큰의 키(Key, K)•밸류(Value, V)를 저장하여 다음 토큰 생성에 재사용하는 메모리이다.
- **동적 배치(Dynamic Batching)**: 실행 중인 요청을 도착 시점과 상태에 따라 배치에 추가•제거하는 방식.
- **메모리 대역폭(Memory Bandwidth)**: 단위 시간에 메모리와 연산 장치 사이에서 전송할 수 있는 데이터 양을 나타낸다.

</details>

- **평균 토큰 간 지연**: 전체 생성 구간을 토큰 간격 수로 나눈 값
- **지연•속도 역관계**: 낮은 TPOT일수록 높은 출력 속도
- **디코드 지연**: KV Cache 대역폭•배치•동시성의 영향

#### 한줄 요약
- 낮은 **TPOT** 기반 빠른 스트리밍 지속 속도

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **로짓(Logit)**: 다음 토큰 후보마다 모델이 계산한 정규화 전 점수.
- **샘플러(Sampler)**: 로짓 분포와 생성 설정을 바탕으로 다음 토큰을 선택하는 구성요소를 나타낸다.
- **스트리머(Streamer)**: 선택한 토큰을 클라이언트에 순차 전송하고 토큰 간 도착 시간을 측정하는 구성요소이다.

</details>

```text
[TPOT(토큰당 출력 지연) 계측 아키텍처]
├── [디코드 스케줄러 (Decode Scheduler)]
│   ├── 반복 레벨 연속 배치(Iteration-level Batching)
│   └── 동시 디코딩 슬롯 및 처리 우선순위 조정
├── [KV Cache 매니저 (KV Cache Manager)]
│   ├── 과거 K/V 벡터 메모리 버스 대역폭 인출
│   └── 신규 생성 토큰 K/V 캐시 추가 갱신
├── [자기회귀 디코딩 엔진 (Autoregressive Engine)]
│   ├── 단일 토큰 순전파 및 차기 로짓(Logit) 산출
│   └── 메모리 대역폭 바운드(Memory-bound) 연산
└── [샘플러 및 스트리머 (Sampler & Streaming Egress)]
    ├── 온도/Top-p 기반 토큰 선택
    └── 토큰 간 도착 시간(Inter-token Gap) 계측
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 디코드 스케줄러 | 활성 요청 간 연속 배치(Continuous Batching) 스케줄링 및 슬롯 조정 |
| KV Cache 매니저 | GPU HBM 메모리로부터 과거 K/V 텐서 로드 및 신규 토큰 캐시 갱신 |
| 자기회귀 디코딩 엔진 | 단일 토큰 순전파를 통해 다음 토큰 어휘 확률 로짓(Logit) 산출 |
| 샘플러 및 스트리머 | 샘플링 알고리즘으로 토큰 결정 및 클라이언트 스트리밍 간격 계측 |

#### 한줄 요약
- **스케줄러•캐시**와 엔진•샘플러•스트리머 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **토큰 간 지연(Inter-token Latency)**: 연속한 두 출력 토큰의 수신 시각 차이로 측정한 생성 간격이다.
- **신규 키-값 추가(New Key-Value Addition, New KV Addition)**: 선택한 토큰의 K•V를 캐시에 덧붙여 다음 디코드 단계에서 재사용하는 과정.

</details>

```text
┌──────────── 생성 종료 전 반복 ────────────┐
│ 스케줄러                                  │
│   │ 1. 활성 요청 배치 편성                │
│   ▼                                       │
│ KV Cache                                  │
│   │ 2. 이전 키•값 조회                    │
│   ▼                                       │
│ 모델 엔진                                 │
│   │ 3. 다음 토큰 로짓 계산                │
│   ▼                                       │
│ 샘플러                                    │
│   │ 4. 토큰 선택•신규 값 추가             │
│   ▼                                       │
│ 스트리머                                  │
│   └ 5. 토큰 전송•간격 기록                │
└───────────────────────────────────────────┘
```

### 동작 원리

1. 활성 요청 배치 편성: 실행 가능한 요청의 **디코드 순서** 결정
2. 이전 키•값 조회: 요청별 과거 문맥의 **캐시 데이터** 전달
3. 다음 토큰 로짓 계산: 모델 계층의 후보별 **생성 점수** 산출
4. 토큰 선택•신규 값 추가: 다음 토큰 확정과 **키•값 캐시** 확장
5. 토큰 전송•간격 기록: 수신 시각 차이로 **토큰 간 지연** 측정

#### 한줄 요약
- **배치•캐시 조회**와 로짓•선택•전송의 토큰별 반복

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **처리량(Throughput)**: 단위 시간에 서버가 처리하는 전체 요청이나 토큰의 총량을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.

</details>

| 구분 | TTFT | TPOT | 처리량 |
|:---|:---|:---|:---|
| 적용 기준 | **초기 반응성 관리** | **개별 스트리밍 속도 관리** | **서버 전체 자원 효율 관리** |
| 핵심 특징 | 첫 응답의 **초기 지연** | 출력 토큰당 **평균 생성 지연** | 단위 시간의 **전체 처리량** |
| 한계 | **지속 생성 속도 미반영** | **초기 대기•완료 시간 미반영** | **개별 사용자 지연 미반영** |

#### 한줄 요약
- 시작은 **TTFT**, 지속은 **TPOT**, 전체 효율은 처리량

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대역폭 병목(Bandwidth Bottleneck)**: KV 캐시를 읽는 속도가 연산 속도를 따라가지 못해 디코드가 지연되는 상태를 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **배치 상한(Batch Limit)**: 서버 효율을 높이면서 개별 요청의 꼬리 지연을 제한하도록 동시에 처리할 요청 수를 제한한 값으로 정의된다.
- **95백분위 토큰 간격(95th Percentile Inter-token Latency, p95 Inter-token Latency)**: 전체 토큰 간 지연의 95%가 이하에 놓이는 경계로 불규칙한 정지를 드러내는 지표.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| KV Cache 읽기의 **메모리 대역폭 병목** | **KV 공유•저정밀 캐시•배치 최적화** | 토큰 간 지연 **절감** |
| 과대 동적 배치의 **개별 지연 증가** | **지연 목표별 배치 상한** 설정 | 꼬리 지연 **완화** |
| 불규칙한 **토큰 간 정지** | 토큰별 시각과 **p95 간격 계측** | 평균값의 병목 은폐 **방지** |

#### 한줄 요약
- **배치 효율•p95 토큰 간격** 동시 측정

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **키-값 공유(Key-Value Sharing, KV Sharing)**: K•V 헤드 중복을 줄여 캐시 대역폭을 절감하는 기법을 뜻하며, 복잡한 문제 해결과 동적 환경 적응에 필수적인 역할을 수행한다.
- **캐시 양자화(Cache Quantization)**: K•V 정밀도를 낮춰 전송 데이터량을 줄이는 방식.
- **동시 요청 상한(Concurrent Request Limit)**: 과대 배치가 병목일 때 한 번에 디코드할 요청 수를 줄여 꼬리 지연을 완화하는 제어 기법이다.

</details>

- 인간-AI 간 실시간 인터랙션의 유창성과 스트리밍 독해 편의성을 좌우하는 **LLM 디코딩 성능 및 GPU 메모리 대역폭 효율의 핵심 서비스 품질 지표(TPOT / Inter-Token Latency / Memory Bandwidth Bound / Continuous Batching / GQA & KV Quantization)의 표준 척도**로 확고히 자리 잡았으며, 분산 서빙 및 추측 디코딩(Speculative Decoding) 도입의 주요 평가 기준으로 활용되는 가운데, 실무 스트리밍 서빙 인프라 설계 시에는 **인간의 읽기 속도를 상회하는 50ms 미만(20+ TPS)의 안정적 TPOT 유지, 불규칙한 끊김 현상을 포착하기 위한 P95/P99 토큰 간 지연(ITL) 편차 모니터링, 추측 디코딩(Speculative Decoding) 및 FP8 KV 캐시 양자화를 결합한 디코딩 가속 엔진 적용**을 결합하여 완벽한 실시간 텍스트 생성 유창성과 서빙 비용 효율성을 완성

#### 한줄 요약
- **p95 TPOT 병목**에 따라 캐시•배치 대책 결정
