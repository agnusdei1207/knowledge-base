## 미리 알고가기

- **TPOT (Time Per Output Token)**: 첫 토큰 뒤 평균 생성 간격
- **TTFT (Time To First Token)**: 요청부터 첫 토큰까지의 시간
- **KV 캐시 (Key-Value Cache)**: 이전 토큰의 어텐션 값을 재사용하는 메모리
- **GQA (Grouped-Query Attention)**: 질의 헤드가 키·값을 공유하는 어텐션 구조
- **SLO (Service Level Objective)**: 토큰 간 허용 지연 기준
- **E2E Latency (End-to-End Latency)**: 요청부터 마지막 토큰까지 소요 시간


## Ⅰ. 개요

- **정의/개념**: 첫 토큰 뒤 토큰당 평균 생성 시간
- **배경/필요성**: 스트리밍·디코드 병목 측정

### 쉽게 이해하기 (학습용)
- 답이 시작된 뒤 다음 단어들이 얼마나 빠르게 이어지는지 나타냄

## Ⅱ. 특징

- 첫 토큰을 뺀 디코드 시간에서 계산한다
- 역수는 요청당 토큰 생성 속도에 대응한다
- 큰 배치는 효율을 높이나 개별 지연을 늘릴 수 있다
- KV 캐시·메모리 대역폭이 지연을 좌우한다

### 쉽게 이해하기 (학습용)

- TPOT가 작을수록 첫 답 뒤 문장이 더 빠르게 이어진다

## Ⅲ. 구성요소 및 구조

| 구성 요소 | 설명 |
|:---|:---|
| Decode Scheduler | 활성 요청을 배치 단위로 편성 |
| Model Engine | 계층별 다음 토큰 연산 수행 |
| KV Cache Manager | 과거 키·값 읽기 및 새 값 추가 |
| Sampler | 로짓에서 다음 토큰 선택 |
| Streamer | 토큰 전송 및 분포 기록 |

> 요약: 디코드·전송 시각이 토큰별 생성 간격을 만듦

### 쉽게 이해하기 (학습용)

- 각 반복에서 과거 메모리를 읽어 다음 Token을 고르고 전송한 뒤 새 메모리를 추가함

## Ⅳ. 원리 및 절차 흐름도

```text
시각수집
↓
간격계산
↓
조건분해
↓
병목조정
↓
회귀검증
```

| 절차 | 설명 |
|:---|:---|
| 시각수집 | 토큰별 수신 시각을 기록함 |
| 간격계산 | 토큰 간 생성 평균 지연 계산함 |
| 조건분해 | 배치·길이·환경별 영향 분석함 |
| 병목조정 | 커널·배치·양자화 등을 적용함 |
| 회귀검증 | 품질 및 성능 지표 검증함 |

> 요약: 토큰 간 지연을 조건별 분해해 병목을 조정함

### 쉽게 이해하기 (학습용)

- 평균과 갑자기 멈추는 꼬리 간격을 함께 봄

## Ⅴ. 종류 및 비교

| 판단 기준 | TTFT | TPOT | 처리량 |
|:---|:---|:---|:---|
| 관점 | 첫 응답 지연 | 토큰 간 지연 | 전체 처리량 |
| 적용 기준 | 초기 반응성 관리 | 스트리밍 속도 관리 | 서버 자원 관리 |
| 최적화 충돌 | 배치 대기 축소 | 캐시·배치 조정 | 배치·동시성 확대 |

> 요약: 초기·개별 생성·전체 처리량을 따로 관리함

### 쉽게 이해하기 (학습용)

- 시작 속도와 한 사람의 이어쓰기 속도, 서버 전체 생산량은 서로 다른 목표임

## Ⅵ. 실무 사례

- 대화·음성 서비스는 평균보다 꼬리 지연과 변동성을 중시함
- 짧은 출력은 TPOT 표본이 적어 전체 완료 시간과 함께 해석함

### 쉽게 이해하기 (학습용)

- 큰 배치는 서버 효율을 높여도 개인의 생성 간격을 늘릴 수 있다

## Ⅶ. 결론

- TPOT는 디코드 구간의 토큰당 지연으로 생성 속도임
- 자원·캐시·배치를 분석해 생성 품질을 균형화함

### 쉽게 이해하기 (학습용)

- TPOT는 답이 시작된 뒤 문장이 이어지는 체감 속도를 나타낸다
