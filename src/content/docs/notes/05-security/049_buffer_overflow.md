## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버퍼 오버플로우(Buffer Overflow / CWE-120 & CWE-787)**: C/C++ 등 메모리를 직접 관리하는 저수준 프로그래밍 언어에서, 입력 데이터의 크기를 검증하지 않고 고정된 크기의 메모리 버퍼에 연속 기록할 때, 할당된 경계를 초과하여 인접한 스택 프레임(Saved Frame Pointer, Return Address)이나 힙 메타데이터를 덮어씀으로써 프로그램 비정상 크래시(DoS) 또는 임의 코드 실행(RCE)을 유발하는 메모리 손상 취약점.
- **제어 흐름 하이재킹(Control Flow Hijacking)**: 스택에 저장된 함수의 복귀 주소(RET, Return Address)를 공격자가 주입한 악성 셸코드(Shellcode)의 메모리 주소나 시스템 라이브러리 함수(`system()`) 주소로 변조하여 CPU의 명령어 포인터(EIP/RIP)를 강제 조작하는 공격 기법.

</details>

- 정의/개념: 메모리 경계 붕괴 결함을 다계층에서 통제하기 위해 **소스코드 레벨의 바운드 체크(Bound Check) 및 메모리 안전 언어 전환**, **컴파일러 레벨의 스택 카나리(Stack Canary)**, **CPU/OS 레벨의 데이터 실행 방지(DEP/NX)**, **가상 메모리 주소 무작위화(ASLR/PIE)** 를 결합하는 **하드웨어-소프트웨어 메모리 심층 방어 아키텍처**
- 배경/필요성: `strcpy`, `gets`, `sprintf` 등 경계 검사를 수행하지 않는 레거시 C 표준 함수의 구조적 결함과 컴파일 타임의 자동화된 보호 기제 부재로 인해 발생하는 제어 흐름 탈취 위협을 근원 차단할 요구

#### 한줄 요약
- 메모리 안전 함수와 스택 카나리, 하드웨어 DEP/NX, ASLR을 다계층 결합하여 제어 흐름 하이재킹을 원천 무력화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스택 카나리(Stack Canary / `-fstack-protector`)**: 함수 프롤로그 시점에 지역 변수 버퍼와 복귀 주소(RET) 사이에 임의의 난수(Magic Number / Terminator Canary)를 삽입하고, 함수 에필로그 시점에 해당 난수가 변조되었는지 검증하여 덮어쓰기 감지 시 프로세스를 즉각 비정상 종료시키는 컴파일러 보호 기법.
- **DEP/NX(Data Execution Prevention / No-Execute Bit)**: x86/x64 CPU 아키텍처의 페이지 테이블 엔트리(PTE)에 NX 비트를 설정하여, 스택(Stack)과 힙(Heap) 등 쓰기 가능한 데이터 메모리 영역에서의 CPU 명령어 실행을 하드웨어 레벨에서 원천 금지하는 보호 기술.
- **ASLR(Address Space Layout Randomization)**: 운영체제가 프로세스를 메모리에 로드할 때마다 스택, 힙, 공유 라이브러리(libc)의 기본 베이스 주소를 무작위로 매핑하여, 공격자가 고정된 점프 주소를 예측할 수 없도록 방해하는 기법.

</details>

- **3계층 유기적 심층 방어**: 컴파일러(카나리) $\rightarrow$ 운영체제(ASLR) $\rightarrow$ CPU 하드웨어(DEP/NX)의 빈틈없는 연동
- **공격 단계별 차단 메커니즘**: 덮어쓰기 감지(카나리), 페이로드 실행 거부(DEP), 주소 점프 무력화(ASLR)
- **메모리 안전성(Memory-Safety) 패러다임 전환**: 소스코드 수준에서 Rust, Go, Java 등 메모리 안전 언어로의 현대화 지향

#### 한줄 요약
- 스택 카나리(덮어쓰기 감지), DEP/NX(실행 차단), ASLR(주소 무작위화), 메모리 안전 언어 전환을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **스택 프레임 구조와 오버플로우 메커니즘**:
  - `[ 지역 변수 버퍼 (Buffer) ]` $\rightarrow$ `[ 스택 카나리 (Canary) ]` $\rightarrow$ `[ 이전 프레임 포인터 (SFP) ]` $\rightarrow$ `[ 복귀 주소 (RET) ]`
  - 공격자가 버퍼를 넘쳐 쓰면 반드시 카나리를 거쳐 RET에 도달하므로 카나리가 먼저 훼손됨.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 소스코드 계층: 안전 함수 및 컴파일 검증 ]                         │
│  ├─ 취약 함수 금지: `strcpy()` ➔ `strncpy()`, `strlcpy()` 대체          │
│  └─ 메모리 안전 언어 전환: Rust (소유권 시스템 기반 컴파일 시점 메모리 검증)│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼ (GCC / Clang 컴파일)
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 컴파일러 보호 계층 (Compiler Stack Protection) ]                  │
│  ├─ 스택 카나리: `-fstack-protector-all` (버퍼와 RET 사이에 난수 주입)  │
│  └─ 위치 독립 실행 파일: `-fPIE -pie` (코드 세그먼트 주소 무작위화 지원)│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼ (OS 메모리 로드 및 런타임 실행)
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 운영체제 및 CPU 하드웨어 방어 계층 (OS & Hardware Protection) ]    │
│  ├─ OS 커널 ASLR: `/proc/sys/kernel/randomize_va_space = 2`             │
│  │   └─ 스택, 힙, 라이브러리(libc) 주소를 실행 시마다 무작위 셔플링     │
│  └─ CPU 하드웨어 DEP/NX: W^X (Write XOR Execute) 원칙 강제              │
│      └─ [ 데이터 영역(Stack/Heap)에 실행 권한(X) 완전 박탈 ➔ SIGSEGV ] │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 소스코드 안전 함수 적용에서 시작하여 컴파일러의 카나리 주입을 거쳐 OS/CPU의 ASLR 및 DEP 하드웨어 차단으로 이어지는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **안전 함수 라이브러리** | 입력 버퍼의 크기(Bound)를 명시적으로 검증하는 C11 표준 안전 함수(`strncpy_s` 등) | Source-Level |
| **스택 카나리 (Canary)** | 스택 덮어쓰기 발생 시 함수 종료 전 변조 여부를 판별하여 프로세스를 즉시 강제 종료 | Compiler-Level |
| **위치 독립 실행 (PIE)** | 바이너리의 코드(Text) 세그먼트까지 메모리 상에 무작위 주소로 로드되도록 지원 | PIE Compiler |
| **ASLR (주소 무작위화)** | 프로세스 기동 시 가상 메모리 레이아웃(Stack, Heap, mmap)의 베이스 오프셋 무작위화 | OS Kernel |
| **하드웨어 DEP/NX** | 페이지 테이블 수준에서 데이터 메모리 영역의 코드 실행을 하드웨어(CPU) 단위에서 차단 | CPU Hardware |

#### 한줄 요약
- 안전 함수, 스택 카나리, PIE 컴파일, OS ASLR, CPU 하드웨어 DEP/NX가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **W^X 원칙 (Write XOR Execute)**: 메모리 페이지는 "쓰기 가능(Writable)"하거나 "실행 가능(Executable)"해야 하며, 두 권한을 동시에 가질 수 없도록 강제하여 코드 주입 공격을 원천 차단하는 현대 OS 메모리 보호 대원칙.

</details>

```text
1. [취약 함수 호출] 공격자가 128바이트 버퍼에 512바이트 크기의 셸코드 및 조작된 복귀 주소 입력
            │
            ▼
2. [버퍼 경계 초과 쓰기] 버퍼를 넘어 스택 카나리 영역과 함수 복귀 주소(RET) 영역까지 메모리 덮어쓰기 집행
            │
            ▼
3. [함수 에필로그 카나리 검증]
    ├─ 컴파일러가 삽입한 `__stack_chk_fail()` 루틴이 스택 카나리 값의 훼손(변조)을 실시간 감지
    └─ [변조 감지 즉시 프로세스 강제 크래시(Crash) 유발 ➔ 제어권 탈취 1차 선제 차단]
            │
            ├─ [만일 정보 유출로 카나리를 우회한 경우: 2차/3차 방어선 작동]
            ▼
4. [ASLR 주소 난수화 방어] 공격자가 고정된 라이브러리 주소로 점프를 시도하나, ASLR에 의해 주소 불일치(Segmentation Fault)
            │
            ▼
5. [하드웨어 DEP/NX 최종 차단] 스택 영역에 주입된 셸코드가 실행되려는 순간 CPU가 NX 비트 위반 인터럽트 발생 ➔ [프로세스 즉시 사살]
```

**동작 원리**

1. **경계 파괴 시도 인지**: 스택 메모리 상의 보호 난수(Canary)가 덮어써지는 즉시 실행 중단
2. **비정상 흐름 차단**: 조작된 RET 주소로 CPU 제어권이 넘어가기 전에 프로세스를 사전 종료
3. **주소 예측성 파괴**: 실행 시마다 매핑되는 가상 주소 엔트로피(Entropy)를 높여 무작위 대입 방해
4. **명령어 실행 통제**: 데이터 영역(스택/힙)에 CPU 명령어가 페치(Fetch)되는 즉시 예외 인터럽트 발생
5. **다중 장애 격리**: 하나의 방어선이 우회되더라도 후속 하드웨어 방어선에서 침해를 완벽 봉쇄

#### 한줄 요약
- 버퍼 초과 쓰기, 카나리 훼손 감지 강제 종료, ASLR 주소 불일치, 하드웨어 DEP 실행 차단 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **메모리 3대 보호 기법 비교**: 스택 카나리(Compiler), DEP/NX(Hardware/OS), ASLR(OS Kernel)의 비교.

</details>

| 비교 항목 | 스택 카나리 (Stack Canary) | 데이터 실행 방지 (DEP / NX) | 주소 공간 무작위화 (ASLR / PIE) |
|:---|:---|:---|:---|
| **보호 메커니즘** | **스택 프레임 내 난수 무결성 검증** | **데이터 메모리 영역의 코드 실행 권한 박탈**| **스택/힙/라이브러리 베이스 주소 난수화** |
| **방어 집행 주체** | **컴파일러 (GCC `-fstack-protector`)** | **CPU 하드웨어 (MMU) + OS 커널** | **운영체제(OS) 가상 메모리 로더** |
| **핵심 방어 목표** | **스택 RET 주소 덮어쓰기 감지 및 차단** | **스택/힙에 주입된 악성 셸코드 실행 차단** | **공격자의 고정된 타깃 점프 주소 예측 방해**|
| **우회 공격 기법** | 카나리 값 메모리 유출(Leak), BSS 덮어쓰기| **ROP (Return-Oriented Programming)** | 메모리 주소 유출(Memory Leak) 취약점 결합 |
| **시스템 오버헤드** | 극히 미미 (함수 시작/종료 시 비교 연산) | **전혀 없음 (하드웨어 MMU 수준 처리)** | 극히 미미 (프로세스 로드 시 1회 연산) |

#### 한줄 요약
- 스택 카나리는 덮어쓰기 감지, DEP/NX는 셸코드 실행 거부, ASLR은 점프 주소 은닉을 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Checksec 바이너리 검증**: 컴파일 완료된 실행 파일(ELF, PE)에 `CANARY`, `NX`, `PIE`, `RELRO` 등 4대 메모리 보호 플래그가 누락 없이 적용되었는지 정적으로 자동 검사하는 보안 감사 도구.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경계 검사를 수행하지 않는 레거시 C 함수(`strcpy`, `gets`) 사용으로 인한 **스택 오버플로우 RCE 취약점 발생** | **C11 표준 안전 함수(`strncpy_s` 등) 전환 및 메모리 안전 언어(Rust) 도입** 의무화 | 메모리 경계 초과 기록 결함 100% 원천 예방 및 컴파일 시점 메모리 안전성 확보 |
| 개발자가 컴파일 플래그를 누락하여 **카나리와 NX가 비활성화된 취약한 바이너리가 운영망에 배포** | **CI/CD 빌드 파이프라인에 Checksec 도구 연동 및 `-fstack-protector-all`, `-Wl,-z,noexecstack` 강제** | 보호 플래그 누락 바이너리의 프로덕션 배포 100% 원천 차단 |
| 스택 카나리만 단독 적용하여 **힙 오버플로우 및 Return-to-libc / ROP 우회 공격에 시스템 장악** | **스택 카나리 + Full ASLR + 하드웨어 DEP/NX + Full RELRO 동시 다층 적용** | 단일 방어선 우회 시에도 후속 하드웨어 및 커널 방어선에 의해 최종 공격 완벽 무력화 |

#### 한줄 요약
- 안전 함수/Rust로 원인을 제거하고, Checksec으로 플래그를 강제하며, 카나리/DEP/ASLR을 다층 적용한다.

## Ⅶ. 결론

- 저수준 메모리 조작 결함으로 인한 시스템 제어권 탈취를 방지하는 **버퍼 오버플로우 다층 방어 아키텍처**는 시스템 보안의 가장 기본적이면서 치명적인 핵심 영역이며, 실무 구현 시 **메모리 안전 언어(Rust) 전환 및 시큐어 코딩**, **컴파일러 스택 카나리 및 PIE 적용**, **CPU 하드웨어 DEP/NX 및 커널 ASLR의 전면 활성화**, **CI/CD 파이프라인 내 Checksec 자동화 검증**을 통합 구축하여 무결점 시스템 실행 환경을 완성

#### 한줄 요약
