## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버퍼 오버플로우(Buffer Overflow)**: 프로그램이 메모리 버퍼에 데이터를 기록할 때 할당된 경계 크기를 초과하여 인접한 메인 메모리 영역 및 반환 주소(SFP/RET)를 무단 덮어쓰는 구조적 취약점.

</details>

- 정의/개념: 버퍼 경계를 넘어 제어 흐름을 바꾸는 **버퍼 오버플로우**
- 배경/필요성: 무제한 복사 함수는 **반환 주소•인접 메모리** 손상 유발

#### 한줄 요약

- 데이터 입력 시 배열 경계 길이를 엄격히 검증하고, 스택 카나리, DEP, ASLR 메커니즘을 다층 연계함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스택 카나리(Stack Canary)**: 함수 프레임 생성 시 반환 주소(RET) 바로 앞에 삽입되는 무작위 값으로, 함수 반환 전 무결성을 검사하여 오버플로우를 감지하는 보호 기법.
- **데이터 실행 방지(Data Execution Prevention, DEP)**: 스택, 힙 등 데이터 메모리 영역에 실행 불가(NX) 속성을 부여하여 셸코드 실행을 차단하는 기술.
- **실행 불가(No-eXecute, NX)**: CPU 하드웨어 단에서 데이터 저장 전용 메모리 페이지의 코드 실행을 물리적으로 거부하는 기술.
- **주소 공간 배치 무작위화(Address Space Layout Randomization, ASLR)**: 프로세스 실행 시마다 스택, 힙, 라이브러리 메인 주소를 난수화하여 메모리 주소 예측을 방해하는 기술.
- **위치 독립 실행 파일(Position Independent Executable, PIE)**: 바이너리 코드 섹션 자체의 주소를 무작위화하여 ASLR 방어를 극대화하는 컴파일 기술.

</details>

- 메모리 경계 초과 쓰기에 따른 반환 주소 오염 및 제어 흐름(Control Flow) 강제 전환.
- **스택 카나리**를 통한 프레임 반환 직전 메모리 변조 실시간 감지 및 비정상 종료 처리.
- **PIE**와 **ASLR**에 의한 메모리 주소 무작위화 및 **DEP/NX**에 의한 데이터 영역 코드 실행 원천 차단.

#### 한줄 요약

- 소스 코드 단의 길이버퍼 검사와 컴파일러 카나리, OS 레벨의 DEP/ASLR을 결합하여 메모리 변조를 다층 방어함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 안전 언어(Memory Safe Languages)**: Rust, Go, Java 등 컴파일러 및 런타임 차원에서 배열 경계 검사(Bounds Check)와 자동 메모리 관리를 강제하여 버퍼 오버플로우를 근본 차단하는 언어.

</details>

```text
버퍼 오버플로 다층 방어
├─ 입력•길이: 데이터 크기•버퍼 필요량 결정
├─ 안전 코드: 경계 검사•안전한 접근
├─ 컴파일러: 카나리•PIE 삽입
├─ 운영체제: DEP•ASLR 적용
└─ 검증•감시: 경계 시험•크래시 추적
```

| 구성요소 | 책임 |
|:---|:---|
| 입력•길이 | 수신 데이터의 실제 크기 파악 및 최대 할당 버퍼 정의 |
| 안전 코드 | strncpy, snprintf 등 경계 안전 함수 사용 및 **메모리 안전 언어** 채택 |
| 컴파일러 | 바이너리 빌드 시 **스택 카나리** 및 **PIE(-pie)** 옵션 강제 |
| 운영체제 | 커널 수준 **DEP/NX** 및 **ASLR**을 적용하여 임의 셸코드 실행 억제 |
| 검증•감시 | 퍼징(Fuzzing) 테스트 및 바이너리 보호 속성(Checksec) 자동 검증 |

#### 한줄 요약

- 안전한 시큐어 코딩 및 메모리 안전 언어 사용, 컴파일러 보호옵션과 OS 커널 하드닝을 유기적으로 연계함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **퍼징(Fuzzing)**: 무작위 및 비정상 경계 입력값을 대량 주입하여 메모리 크래시 및 오버플로우 취약점을 자동으로 검출하는 동적 테스트 기법.
- **크래시(Crash)**: 메모리 세그먼테이션 오류(SIGSEGV) 등으로 인해 프로세스가 비정상 종료되는 현상.
- **길이 미검사 복사(Unchecked Buffer Copy)**: strcpy, gets 등 경계 검사가 없는 취약한 표준 함수를 호출하는 단계.
- **버퍼 경계 초과 쓰기(Out-of-bounds Write)**: 데이터가 할당된 스택 버퍼 크기를 초과하여 덮어쓰이는 단계.
- **카나리•반환 주소 손상(Canary & RET Overwrite)**: SFP, RET 및 카나리 매직 넘버가 오염되는 단계.
- **카나리 무결성 검사(Canary Verification)**: __stack_chk_fail()을 호출하여 변조를 감지하는 단계.
- **변조 제어 흐름 전환 시도(Control Flow Hijacking)**: 오염된 RET 주소를 통해 셸코드나 ROP 가젯으로 분기하는 단계.

</details>

```text
버퍼보다 긴 입력
        │
        ▼
1. 길이 미검사 복사
        │
        ▼
2. 버퍼 경계 초과 쓰기
        │
        ▼
3. 카나리•반환 주소 손상
        │
        ▼
4. 카나리 무결성 검사
        │
        ├─ 변조 탐지 ── 비정상 종료
        │
        └─ 변조 미탐지 ── 5. 변조 제어 흐름 전환 시도
                                  │
                                  ▼
                         DEP•ASLR 차단 또는 실행
```

### 동작 원리

1. 길이 미검사 복사: 입력 크기 검증 없이 고정 크기 스택 버퍼에 데이터 전송.
2. 버퍼 경계 초과 쓰기: 버퍼 경계를 넘어서는 메모리 오버플로우 집행.
3. 카나리•반환 주소 손상: 스택 카나리 값 및 함수 반환 주소(RET) 덮어쓰기.
4. 카나리 무결성 검사: 함수 종료 시 카나리 값을 대조하여 변조 탐지 시 즉시 프로세스 강제 종료.
5. 변조 제어 흐름 전환 시도: 카나리 우회 시 DEP/NX 및 ASLR 방어벽과 차단 대조.

#### 한줄 요약

- 오버플로우 발생 시 카나리 검사로 1차 차단하며, 2차로 DEP 및 ASLR을 통해 셸코드 집행을 차단함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **메모리 보호 계층 선택 기준(Memory Defense Criteria)**: 스택 프레임 보호는 Stack Canary, 실행 방지는 DEP/NX, 주소 정적 맵핑 방지는 ASLR/PIE를 계층적 적용하는 선택 기준.

</details>

| 메모리 보호 유형 | 카나리 | DEP/NX | ASLR |
|:---|:---|:---|:---|
| 적용 기준 | 스택 오염 감지 | 데이터 실행 방지 | 주소 예측 난도 증가 |
| 핵심 특징 | **스택 카나리**로 오염 탐지 | **DEP/NX**로 데이터 코드 실행 차단 | **ASLR**로 메모리 주소 무작위화 |
| 한계 | 값 노출•비검사 영역 손상 | ROP 코드 재사용 공격 가능 | 주소 누출(Leak) 시 무력화 가능 |

#### 한줄 요약

- 카나리의 스택 변조 탐지, DEP의 데이터 메모리 실행 차단, ASLR의 주소 난수화를 계층 결합함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MITRE CWE-787**: 할당된 버퍼 영역 밖의 메모리에 데이터를 기록하는 버퍼 오버플로우 약점 명세.
- **산출물 검사(Artifact Security Check)**: Checksec 등 자동화 도구로 배포 바이너리의 Canary, NX, PIE, RELRO 적용 여부를 검증하는 절차.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경계 미검사 함수 사용 | **MITRE CWE-787** 가이드 준수 및 strlcpy 등 안전 함수 전환 | 1차 버퍼 오버플로우 결함 완전 차단 |
| 단일 방어 실패 시 코드 실행 | **스택 카나리**, **PIE**, **DEP/NX**, **ASLR** 컴파일러/OS 옵션 동시 적용 | 메모리 덮어쓰기 성공 시에도 익스플로잇 무력화 |
| 빌드 파이프라인 보안 누락 | **산출물 검사** 및 **퍼징** 자동화 파이프라인 연계 | 취약 바이너리의 실운영 환경 배포 사전 선제 억제 |

#### 한줄 요약

- 입력 데이터 길이를 버퍼 할당 크기와 사전 대조하고, 컴파일 타임 보호 옵션(Canary, PIE)과 런타임 하드닝(DEP, ASLR)을 전면 적용함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **다층 보호(Defense-in-Depth for Memory)**: 소스 코드 수준의 안전한 경계 검사부터 컴파일러 카나리, OS 커널 실행 제한(DEP/ASLR)까지 포괄하는 메모리 심층 방어 체계.

</details>

- **다층 보호** 원칙에 따라 소스 단 안전 함수 적용 및 **스택 카나리**, **DEP/NX**, **ASLR** 보안 메커니즘을 전 계층 적용.

#### 한줄 요약

- **경계 검사•Canary•DEP•ASLR**을 전 계층 적용
