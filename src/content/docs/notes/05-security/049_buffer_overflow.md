## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **버퍼 오버플로우 (Buffer Overflow)**: 100글자만 들어가는 컵(버퍼)에 200글자의 물을 들이부어서, 물이 넘쳐 옆에 있는 중요 메모리(돌아갈 주소 등)까지 덮어버리는 치명적 메모리 파괴 공격이다.

</details>

- 정의: 프로그램이 메모리 버퍼에 데이터를 기록할 때 할당된 경계 크기를 초과하여, 인접한 메인 메모리 영역 및 반환 주소(RET)를 무단으로 덮어쓰는 구조적 취약점이다.
- 배경: C언어의 `strcpy` 같은 함수가 들어오는 데이터의 '길이'를 묻지도 따지지도 않고 무제한 복사하기 때문에, 메모리 경계가 붕괴하기 때문이다.

#### 한줄 요약

- 그릇 크기를 무시하고 데이터를 들이부어서, 옆에 있던 중요 시스템 제어권까지 다 덮어버리는 공격이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **스택 카나리 (Stack Canary)**: 물이 넘치는지 감시하려고 스택(컵) 끝에 세워둔 '광산의 카나리아(난수)'다. 이거 건드리면 해킹으로 간주하고 프로그램을 강제 종료시킨다.
- **DEP/NX (데이터 실행 방지)**: 메모리 데이터 영역에 해커 코드가 들어와도 "여긴 데이터 창고니까 코드 실행 절대 금지!" 하고 CPU가 물리적으로 원천 차단하는 방패다.
- **ASLR (주소 무작위화)**: 해커가 시스템 주소를 못 맞추게, 프로그램 실행할 때마다 스택이나 힙 메모리 주소를 윷놀이판처럼 무작위로 섞어버리는 기술이다.

</details>

- **제어 흐름 전환**: 메모리 경계를 초과한 덮어쓰기로 함수 반환 주소(RET)를 오염시켜, 해커가 원하는 악성 셸코드(Shellcode) 흐름으로 강제 전환한다.
- **컴파일러 방어 (카나리)**: 스택 프레임 반환 직전에 카나리 매직 넘버 변조 여부를 실시간 감지하여, 뚫리면 프로세스를 비정상 종료(크래시)시킨다.
- **OS 커널 방어 (DEP/ASLR)**: CPU 레벨의 DEP/NX로 데이터 영역 코드 실행을 원천 원천 차단하고, ASLR/PIE로 메모리 주소를 섞어 해커의 점프 주소 예측을 방해한다.

#### 한줄 요약

- 카나리로 넘치는 걸 감지하고, DEP로 실행을 막고, ASLR로 위치를 섞어 해커를 바보로 만드는 다층 방어다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메모리 안전 언어 (Memory Safe Languages)**: Rust, Go, Java처럼 아예 언어 차원에서 경계선을 넘어가는 걸 컴파일러가 쳐내서, 버퍼 오버플로우 자체가 안 발생하는 안전한 언어다.

</details>

```text
[ 버퍼 오버플로우 다층 방어 아키텍처 ]

[ 1. 소스 코드 (입력 검증) ] ── ("100글자 넘는 데이터는 아예 안 받게 길이 검사함")
      │
      ▼
[ 2. 메모리 안전 함수 사용 ] ── ("strcpy 버리고 strncpy 써서 안전하게 경계선 내에서만 복사함")
      │
      ▼
[ 3. 컴파일 방어 (카나리/PIE) ] ── ("빌드할 때 스택 끝에 카나리아 새(난수) 심어둠")
      │
      ▼
[ 4. OS 메모리 주소 섞기 (ASLR) ] ── ("실행할 때마다 메모리 주소를 무작위로 섞어버림")
      │
      ▼
[ 5. OS 데이터 실행 차단 (DEP) ] ── ("어찌저찌 뚫려도, 데이터 창고에선 악성 셸코드 실행 금지함")
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **입력 및 길이 검증** | 데이터 받을 때 **100글자 컵에 맞는지 데이터 길이를 검사함** | Source |
| **안전 함수 및 언어** | 경계 검사 안 하는 함수 버리고, **메모리 안전 언어(Rust 등) 채택함** | Safe Lang |
| **컴파일러 (카나리)** | 덮어쓰기 감지용 **카나리 매직 넘버를 스택에 자동 삽입함** | Canary |
| **OS 난수화 (ASLR/PIE)** | 해커가 공격 주소 못 찾게 **실행할 때마다 메모리 위치를 섞음** | ASLR |
| **OS 실행 방지 (DEP)** | 해커 코드가 들어와도 **데이터 영역에선 실행 자체를 거부함** | DEP |

#### 한줄 요약

- 소스 짤 땐 함수 조심하고, 컴파일 땐 카나리 박고, 런타임엔 OS가 메모리를 섞고 실행을 컷한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ 오버플로우 공격 및 카나리 철저한 방어 흐름 ]

┌──────────────────────────────┐
│ 1. [길이 미검사 취약점 함수 호출]
│ ("해커가 200글자 폭탄 데이터를 들고 무지성 복사 함수(strcpy)로 진입함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [버퍼 경계 초과 쓰기 (Overflow 발생)]
│ ("100글자 컵이 넘치면서 스택에 있던 옆 동네 메모리 구역을 다 덮어버림")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [카나리 및 반환 주소(RET) 손상]
│ ("스택 끝에 있던 카나리아(난수)와 돌아갈 주소(RET)가 해커 코드로 오염됨")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [방어 1: 카나리 무결성 검사]
│ ("함수 끝날 때 보니 카나리아가 죽었네? 변조 감지! 즉시 프로그램 강제 종료(크래시)!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [방어 2: DEP/ASLR 원천 차단 (카나리 우회 시)]
│ ("어찌어찌 카나리 뚫어도, 데이터 영역 실행 금지(DEP) 걸려서 셸코드 실행 실패!")
└──────────────────────────────┘
```

### 동작 원리

1. 길이 미검사 복사: 입력 크기 철저한 검증 없이, 고정 크기 스택 버퍼에 초과 데이터를 밀어 넣음.
2. 경계 초과 쓰기: 버퍼 경계를 무너뜨리며 인접한 메모리 영역(SFP) 덮어쓰기 집행.
3. 반환 주소 손상: 스택 카나리 값 및 함수가 돌아가야 할 반환 주소(RET)를 악성 주소로 변조함.
4. 카나리 무결성 검사: 함수 종료 직전(RET 직전), 훼손된 카나리 값을 대조하여 이상 탐지 시 프로세스 강제 킬(Kill).
5. 셸코드 차단: 카나리를 우회하더라도 DEP/NX가 셸코드 실행을 컷하고, ASLR이 주소 점프를 무력화함.

#### 한줄 요약

- 그릇 넘쳐서 카나리 죽으면 무조건 강제 종료 치고, 그래도 뚫고 들어오면 CPU(DEP)가 쏴 죽인다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 특징 설명 참조)

</details>

| 메모리 보호 기법 | **스택 카나리 (Canary)** | **데이터 실행 방지 (DEP/NX)** | **주소 무작위화 (ASLR/PIE)** |
|:---|:---|:---|:---|
| 핵심 특징 | **지뢰밭(스택 끝)에 심어둔 동작 감지 경보기** | **창고(데이터 영역)에서 무단 총기(코드) 사격 금지** | **적군(해커) 좌표 지도를 매번 무작위로 섞어버리기** |
| 핵심 방어 방식 | 스택 프레임 반환 주소(RET) 직전에 난수를 심고 **덮어쓰기 변조를 감시함** | CPU가 메모리 페이지에 NX 비트를 걸어 **악성 코드 실행을 하드웨어 레벨에서 거부함** | 프로그램 실행 시마다 메모리 주소(스택/힙)를 섞어 **해커의 점프 위치를 숨김** |
| 장점 및 특징 | 오버플로우가 일어나는 순간(덮어쓰기)을 **가장 빠르고 정확하게 적발(크래시)함** | 해커가 자기 코드를 밀어넣어 셸(Shell)을 띄우려는 시도를 **물리적으로 컷함** | 해커가 공격 코드를 어디로 보내야 할지(ROP 등) **주소 예측 자체를 방해함** |
| 한계 및 문제점 | 메모리 덮어쓰기를 하지 않는 기법이나, 카나리 난수값을 알아내면 **우회당함** | 해커 코드를 직접 안 돌리고, 이미 있는 합법적 코드 조각(ROP)을 재조합하면 **방어 불가함** | 메모리 주소가 단 한 번이라도 외부로 유출(Memory Leak)되면 **섞어둔 방패가 다 깨짐** |

#### 한줄 요약

- **카나리** 기반 덮어쓰기 감지용, **DEP** 기반 실행 금지용, **ASLR** 주소 섞기용이다. 셋 다 켜야 안전하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MITRE CWE-787**: "할당된 그릇 밖으로 데이터 붓지 마라" 하고 경고하는 버퍼 오버플로우 글로벌 취약점 명세다.
- **Checksec (산출물 검사)**: 배포하기 전에 빌드된 바이너리 파일을 까보고 "어? 너 카나리 안 걸었네? ASLR 안 켰네?" 하고 자동 검사하는 보안 스캐너 도구다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 개발자가 무심코 쓴 복사 함수 하나에 **메모리 터져서 서버 장악당함** | 데이터 길이를 검사하지 않는 멍청한 구형 C 함수(`strcpy`, `gets` 등)를 무지성 방치함 | **MITRE CWE-787** 기반, 길이 검증이 들어간 안전 함수(`strncpy` 등)로 전면 전환 | 데이터 길이가 초과되어 발생하는 1차적인 메모리 붕괴 취약점 원천 차단 |
| 방어벽(카나리) 하나만 믿고 배째다가 **신종 우회 기법(ROP)에 다 뚫림** | DEP나 카나리 중 하나만 대충 켜놓고, 모든 해킹을 다 막을 수 있다고 착각함 (단일 방어) | **카나리 + DEP/NX + ASLR/PIE** 보호 기법을 컴파일러와 OS 커널 단에서 **동시 다층 적용** | 해커가 하나를 뚫어도 다음 방패에 막혀서 최종 셸코드 악성 실행 절대 불가 |
| 보호 옵션 켜라고 지시했는데 **개발팀이 깜빡하고 그냥 취약하게 배포함** | 빌드할 때 보호 옵션(플래그)을 수동으로 넣게 놔두고, 자동화된 강제 검증 절차를 안 함 | CI/CD 배포 파이프라인에 **Checksec 등 산출물 보안 검사 도구** 연계 및 자동화 강제 | 카나리나 PIE 보호 옵션이 빠진 취약한 바이너리가 운영망에 배포되는 사태 선제 억제 |

#### 한줄 요약

- 길이 확인하는 안전 함수 쓰고, 컴파일할 때 카나리/PIE 옵션 무조건 박고, 빌드 끝나면 Checksec으로 검사해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **다층 철저한 방어 (Defense-in-Depth for Memory)**: 소스코드 검사부터 컴파일러 방어(카나리), OS 커널 제한(DEP)까지 모든 계층에서 해커를 물어뜯는 포괄적 방어 사상.

</details>

- 버퍼 오버플로우는 단일 통제망 우회가 쉬우므로, 소스 코드 레벨에서 안전 함수 및 **메모리 안전 언어** 기반 경계를 검증하고, 컴파일 타임에 **스택 카나리** 활용 심으며, 런타임에 OS 단의 **DEP/NX** 및 **ASLR/PIE** 활용 동시 적용하여 해커의 메모리 조작을 완전히 무력화하는 '다층 철저한 방어(Defense-in-Depth)' 기조를 확립함

#### 한줄 요약

- 소스단 **경계 검사**, 컴파일 **카나리**, 런타임 **DEP•ASLR** 전 계층에 겹겹이 적용해라.
