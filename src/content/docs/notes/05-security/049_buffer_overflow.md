## 미리 알고가기

- **버퍼(Buffer, 버퍼)**: 입력·데이터를 임시 저장하도록 크기를 정해 확보한 메모리 영역
- **버퍼 오버플로(Buffer Overflow, 버퍼 오버플로)**: 쓰기 크기가 버퍼 경계를 넘어 인접 메모리를 손상시키는 취약점
- **스택 카나리(Stack Canary, 스택 카나리)**: 반환 주소 앞의 임의 값을 대조해 스택 덮어쓰기를 탐지하는 보호값
- **DEP/NX(Data Execution Prevention/No-eXecute, 디이피·엔엑스)**: 데이터 메모리 영역의 코드 실행을 금지하는 보호
- **ASLR(Address Space Layout Randomization, 에이에스엘알)**: 코드·라이브러리·스택 주소를 실행마다 무작위 배치
- **PIE(Position Independent Executable, 피아이이)**: 실행 파일도 임의 주소에 배치할 수 있게 만든 바이너리
- **메모리 안전 언어**: 배열 경계와 객체 수명을 실행환경·타입 체계가 검사하는 언어
- **크래시(Crash, 크래시)**: 잘못된 메모리 접근 등으로 프로그램이 비정상 종료되는 현상


- **흐름 기호(↓·→·X)**: 아래·다음·차단의 절차 방향과 금지를 표시
## Ⅰ. 개요

- 정의/개념: 경계 초과 쓰기가 인접 메모리를 손상함
- 기존 한계: 경계 미검사 메모리 쓰기는 인접 영역 손상
- **배경/필요성**: 경계 검사와 다층 실행 방어 적용

### 쉽게 이해하기 (학습용)

- 버퍼 경계를 넘은 쓰기는 인접 메모리와 제어 흐름을 바꾸므로 원천 코드와 실행 환경을 함께 보호해야 한다.

## Ⅱ. 특징

- 경계 초과 쓰기가 인접 데이터와 제어 정보를 손상한다.
- 카나리가 스택 제어 정보의 변조를 탐지한다.
- DEP가 데이터 영역의 코드 실행을 막는다.
- ASLR이 코드 주소 예측을 어렵게 만든다.
- 보호 우회 시 충돌이나 임의 코드 실행으로 이어진다.

### 쉽게 이해하기 (학습용)

- 경계 검사로 결함을 막고 실행 방지·주소 무작위화·스택 보호로 악용 가능성을 낮춘다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 입력/길이 | 데이터 크기 및 버퍼 필요량 결정 |
| 안전 코드 | 경계 검사 및 안전한 접근 구조 |
| 컴파일러 | 카나리·PIE 옵션 바이너리 삽입 |
| 운영체제 | DEP·ASLR로 잔존 악용 제한 |

```text
[외부 입력·길이] → [버퍼 쓰기] → 경계 초과? ─예→ [인접 데이터·제어정보 손상]
                          │ 아니오
                    [정상 처리]

[안전 코드] + [카나리·PIE] + [DEP·ASLR] → 원인 제거·악용 단계 제한
```

### 쉽게 이해하기 (학습용)

- 외부 입력이 고정 크기 버퍼에 복사될 때 경계 검사가 초과 길이를 거부하고 실행 보호가 악용을 억제한다.

## Ⅳ. 원리 및 절차 흐름도

```text
경로식별
   ↓
근본수정
   ↓
빌드보호
   ↓
파일검증
   ↓
검증감시
```

| 절차 | 설명 |
|:---|:---|
| 경로식별 | 입력 크기와 복사 경로 식별함 |
| 근본수정 | 안전한 자료구조/경계 검사함 |
| 빌드보호 | 카나리/DEP 옵션 활성화함 |
| 파일검증 | 최종 바이너리 보호 속성 검증함 |
| 검증감시 | 경계값 검증과 크래시 이력 감사함 |

> 요약: 경로 식별 및 근본 수정 후 빌드/파일 검증함

### 쉽게 이해하기 (학습용)

- 취약한 입력 경로를 찾아 길이 검사를 고친 뒤 실제 산출물에 보호 옵션이 적용됐는지 확인한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 카나리 | DEP/NX | ASLR |
|:---|:---|:---|:---|
| 적용 기준 | 스택 오염 감지 시 | 데이터 실행 방지 시 | 주소 예측 난도 증가 |
| 핵심 특징 | 보호값 변조로 스택 오염 탐지 | 데이터 메모리의 코드 실행 차단 | 메모리 주소 무작위화 |
| 한계 | 값 노출·비검사 영역 손상 | 코드 재사용 공격 가능 | 주소 누출 시 우회 가능 |

> 요약: 변조/실행/주소 예측 단계별 방어 기법임

### 쉽게 이해하기 (학습용)

- 버퍼 오버플로과 대안의 선택 기준을 비교함

## Ⅵ. 실무 사례

- 메모리 안전 언어 전환 우선 적용
- 최종 산출물 보호 옵션 검증
- 주소 노출 결함 제거로 ASLR 강화
- 크래시 시 로그 감시 및 원인 분석

### 쉽게 이해하기 (학습용)

- 사례 1은 신규 구성요소를 메모리 안전 언어로 전환해 경계 오류 자체를 줄인다.
- 사례 2는 컴파일 설정뿐 아니라 배포 바이너리의 보호 옵션을 직접 확인한다.
- 사례 3은 주소 노출을 제거해 ASLR의 위치 예측 방지 효과를 유지한다.
- 사례 4는 반복 크래시를 공격 신호로 감시하고 재현해 취약 경로를 찾는다.

## Ⅶ. 결론

- 경계 오류를 고치고 DEP·ASLR로 악용을 제한함

### 쉽게 이해하기 (학습용)

- 버퍼 오버플로는 안전한 구현과 컴파일·실행 보호를 계층적으로 적용해야 한다.
