## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MFA (다중 인증)**: 비밀번호(아는 것) 하나만 믿지 말고, 휴대폰(가진 것)이나 지문(내 몸)처럼 서로 전혀 다른 성질의 인증 수단을 2개 이상 섞어서 팩트로 본인 확인을 하는 방어 체계다.

</details>

- 정의: 지식(Know), 소유(Have), 생체(Are) 중 서로 다른 카테고리의 2개 이상 독립적 인증 요소를 결합하여 식별하는 팩트 검증 메커니즘이다.
- 배경: 크리덴셜 스터핑(Credential Stuffing)이나 키로거 해킹으로 비밀번호가 팩트로 털려도, 2차 인증 기기(스마트폰 등)가 해커 손에 없으면 계정 탈취를 완벽히 막아낼 수 있기 때문이다.

#### 한줄 요약

- 해커가 내 비밀번호를 털어 가도, 내 지문과 폰이 없으면 로그인 버튼조차 못 누르게 팩트로 틀어막는 거다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지식/소유/생체 요소**: 비밀번호(지식), OTP 앱(소유), 안면인식(생체). 이 중에 서로 다른 동네 2개를 골라야 진짜 MFA다. (비번 치고 PIN 번호 또 치는 건 지식+지식이라 MFA가 아님)
- **피싱 저항성 (Phishing Resistance)**: 해커가 똑같이 생긴 가짜 네이버 로그인 창을 만들어서 내 OTP 번호까지 털어가려고 해도, FIDO2/WebAuthn 기술은 도메인을 팩트로 구별해서 가짜 창엔 서명 자체를 안 해버리는 철벽 특성이다.

</details>

- **팩트 카테고리 독립성**: 지식, 소유, 생체 요소 간 카테고리 독립성을 확보해야 한다. (동일 카테고리 조합은 2-Step 인증일 뿐 진정한 MFA가 아님)
- **팩트 피싱 저항성 방어**: 중간자(MitM) 역프록시 피싱 사이트에 속아 OTP 번호를 넘겨주는 참사를 막기 위해, 도메인 바인딩 기술이 접목된 FIDO2를 팩트로 적용한다.
- **팩트 동등 수준 복구 관리**: 폰을 잃어버려서 초기화할 때, 해커가 헬프데스크의 허점을 노리지 못하도록 본 인증(로그인)과 동등 수준의 신원확인을 팩트로 관리한다.

#### 한줄 요약

- 서로 다른 방식(비번+폰)을 섞고, 가짜 사이트(피싱)에 안 속게 FIDO2를 박고, 폰 잃어버렸을 때 대충 복구해주지 마라.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인증기 등록**: 신입사원이 처음 회사 폰(인증기)을 받았을 때, "이 폰이 내 폰이다"라고 시스템과 폰(공개키)을 팩트로 묶어주는 최초 바인딩 과정이다.
- **비상 계정 (Break-glass Account)**: 사장님 폰 부서지거나 인증 서버 터졌을 때 회사 업무 멈추지 말라고, 팩트로 금고에 봉인해두는 최후의 긴급 비상구다.

</details>

```text
[ MFA 다중 인증 팩트 아키텍처 ]

[ 1. 인증 레벨(AAL) 정책 ] ── ("여긴 1급 비밀 서버니까 무조건 지문+비번(AAL3) 써라 팩트 지정함")
      │
      ▼
[ 2. 인증기 기기 등록 ] ── ("처음 입사할 때 스마트폰(인증기)이랑 사번을 서버에 팩트로 묶음")
      │
      ▼
[ 3. 다중 인증(MFA) 팩트 검증 ] ── ("비번(지식) 치고, 폰(소유)으로 승인 눌러서 교차 팩트 통과함")
      │
      ▼
[ 4. 세션 발급 및 유지 ] ── ("통과하면 세션 토큰 주고, 돈 보내는 중요 작업 땐 다시 물어봄")
      │
      ▼
[ 5. 복구 및 비상(Break-glass) 관리 ] ── ("폰 잃어버렸다고 대충 복구해주지 말고 철저히 팩트 감사함")
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **인증 보증 정책(AAL)** | 서버 중요도에 따라 AAL 레벨별 필요 인증 요소를 **사전에 팩트로 정의함** | Policy |
| **인증기 등록 바인딩** | 최초 로그인 시 사용자 신원을 확정하고 **기기(공개키/시드)를 팩트로 맵핑함** | Register |
| **MFA 팩트 검증기** | 비번 치고 들어온 사람한테 OTP나 푸시 응답(2차)을 **독립적으로 팩트 검증함** | Verify |
| **세션 및 재인증 통제** | 인증 세션을 유지하되, 이체나 비번 변경 땐 **무조건 재인증을 팩트 강제함** | Session |
| **비상 복구/감사** | 기기 분실 대비용 **비상 계정(Break-glass)** 사용 이력을 SIEM으로 팩트 추적함 | Audit |

#### 한줄 요약

- 급 맞춰서 정책 정하고 $\to$ 폰 등록하고 $\to$ 로그인 때 검사하고 $\to$ 돈 보낼 땐 한 번 더 물어보는 게 팩트다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ 피싱 저항성(FIDO) 기반 MFA 팩트 검증 흐름 ]

┌──────────────────────────────┐
│ 1. [사용자 로그인 요청 및 위험도 판정]
│ ("ID 입력 시, 시스템이 '이건 중요 작업이니 MFA 켜!' 하고 팩트 판정함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [일회성 도전값(Challenge) 팩트 발급]
│ ("서버가 Replay(재전송) 방어용 난수(도전값)를 클라이언트로 팩트 전송함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [생체/소유 독립 요소 서명 생성]
│ ("사용자가 지문을 대면, 스마트폰 내장 칩이 도전값에 암호학적 팩트 서명을 함")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 4. [도메인 바인딩 및 서명 팩트 검증 (피싱 차단)]
    │ ("서버가 서명을 풀고, '어? 가짜 피싱 사이트에서 온 거네?' 즉시 팩트 컷!")
    └──────────────┬───────────────┘
                   ▼
    ┌──────────────────────────────┐
    │ 5. [안전 세션 발급 및 고위험 재인증 환류]
    │ ("진짜 사이트 맞으면 통과시키고, 나중에 돈 보낼 땐 3번으로 팩트 롤백시킴")
    └──────────────────────────────┘
```

### 동작 원리

1. 위험도 판정: 요청 업무 위험도(AAL1~3 레벨) 기반으로 필요한 인증 요소 조합을 확정함.
2. 도전값 생성: 재전송 공격 방지를 위해 1회용 난수 Challenge 값을 클라이언트에 발급함.
3. 독립 요소 증명: 스마트폰/보안키(TPM)에서 생체 인식 후 개인키로 도전값을 팩트 전자서명함.
4. 등록 결속 검증: 도메인 URL과 서버에 등록된 공개키를 대조하여, 피싱 중간자 공격을 팩트 기각함.
5. 세션 및 재인증: 인증 통과 세션을 발급하되, 고위험 트랜잭션 시에는 MFA를 재호출(Re-auth)함.

#### 한줄 요약

- 위험도 파악 $\to$ 난수(문제) 던짐 $\to$ 폰이 지문 찍고 서명(답안) 함 $\to$ 가짜 사이트 냄새나면 팩트 컷!

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| MFA 인증 방식 | **SMS / 이메일 OTP** | **앱 푸시 (Push Approval)** | **FIDO2 / WebAuthn** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **집배원(통신사)이 가져다주는 임시 6자리 출입증** | **"너 지금 들어오려는 거 맞지?" 하고 폰에 뜨는 알람** | **절대 복제 불가능한 내 몸속(지문/보안키) 생체 열쇠** |
| 핵심 인증 방식 | 이동통신망(SMS)이나 메일로 6자리 숫자를 보내고 **서버 입력값을 팩트로 대조함** | 모바일 앱 팝업 창에 '승인' 버튼을 띄우고 **사용자 터치를 팩트로 대조함** | 스마트폰 내장 보안칩(TPM)에 저장된 개인키로 **도전값을 전자서명하여 팩트 대조함** |
| 장점 및 특징 | 누구나 휴대폰만 있으면 되므로 **도입이 가장 빠르고 가성비가 팩트로 압도적임** | 6자리 번호 칠 필요 없이 터치 한 번이면 끝나서 **사용자 편의성이 팩트로 뛰어남** | 서버 해킹이나 가짜 피싱 사이트 공격을 당해도 **피싱 저항성 덕분에 팩트로 안 털림** |
| 한계 및 문제점 | 통신사 망이 털리거나 SIM 스와핑(유심 복제) 당하면 **OTP 번호를 해커가 다 팩트로 훔쳐봄** | 해커가 새벽에 푸시 알람을 천 번 쏘면 귀찮아서 **실수로 '승인' 누르는 피로 공격에 팩트 털림** | 구형 브라우저나 디바이스에서는 하드웨어 칩 지원이 안 돼서 **호환성 맞추기가 팩트로 빡셈** |

#### 한줄 요약

- SMS는 **해커가 훔쳐보고**, 푸시는 **귀찮게 해서 뚫고**, FIDO2는 **절대 안 털리지만 세팅이 빡세다**.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-63B-4**: 미국 정부가 "SMS OTP 그만 좀 써라, 해커한테 다 털린다" 하고 팩트로 지정해 둔 인증 지침이다.
- **번호 일치 (Number Matching)**: 해커가 새벽에 앱 승인 버튼 무한대로 쏘는 걸 막기 위해, "그냥 확인 누르지 말고 PC 화면에 뜬 숫자 2자리를 폰에 직접 치세요" 하고 팩트로 강제하는 기능이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| SMS OTP로 잘 썼는데 **해커가 통신사 유심(SIM) 복제해서 다 팩트로 털어감** | SMS는 암호화되지 않은 평문 망이라 SIM 스와핑이나 SS7 망 해킹에 무방비로 팩트 노출됨 | **NIST SP 800-63B-4** 지침 준수 및 중요 계정은 SMS를 버리고 **FIDO2 하드웨어로 팩트 전환** | 가로채기(Interception) 및 중간자 피싱 공격 구조적 팩트 원천 차단 |
| 해커가 새벽에 푸시 100번 쏴서 **직원이 무심코 '승인' 눌렀다가 서버 장악됨** | 사용자가 인증 요청 내용을 안 보고 무지성으로 터치하게 만드는 승인 피로(MFA Fatigue) 팩트 간과 | 푸시 알람 창에 화면 숫자를 의식적으로 입력하게 만드는 **번호 일치(Number Matching) 기능 팩트 강제** | 매크로성 무차별 푸시 스팸 및 사용자 오승인(Human Error) 공격 팩트 무력화 |
| MFA 철통같이 걸어놨는데 **콜센터 전화해서 "폰 잃어버렸어요" 구라 치고 팩트로 뚫음** | IT 헬프데스크의 신원 확인 절차가 허술해서, 소셜 엔지니어링(사회공학 기법)에 복구 절차가 팩트 뚫림 | 복구 및 초기화 절차 시 본 인증과 **동등 보증 강도(Equivalent Assurance)** 확인 및 팩트 감사 강제 | 정상 인증은 빡세면서 복구(Backdoor)는 허술한 보안 불균형 팩트 원천 억제 |

#### 한줄 요약

- SMS 버리고, 푸시 폭탄은 '번호 치기'로 막고, 콜센터 통해 폰 초기화해주는 절차 빡세게 팩트로 잡아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동등 보증 강도 (Equivalent Assurance Level)**: 정문(로그인) 빡세게 지켰으면, 뒷문(폰 분실 초기화)도 똑같이 빡세게 지키라는 보안 관리의 대원칙이다.

</details>

- 지식과 소유를 결합한 MFA는 계정 탈취의 핵심 방패이므로, 피싱 공격에 취약한 SMS 방식은 배제하고 **FIDO2/번호 일치** 기반의 피싱 저항성을 확보하며, 고위험 행위 시 **재인증**과 철저한 **복구 절차 통제(동등 보증 강도)**를 다층 적용하는 팩트 실무 기조를 확립함

#### 한줄 요약

- 피싱은 **FIDO2**, 푸시 테러는 **번호 일치**, 고위험은 **재인증**, 분실 복구는 **동등 강도**로 팩트 통제해라.
