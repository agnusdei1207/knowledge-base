## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **다중 인증(Multi-Factor Authentication, MFA)**: 지식(Something you know), 소유(Something you have), 생체(Something you are) 중 서로 다른 카테고리의 2개 이상 독립적 인증 요소를 검증하는 식별 메커니즘.

</details>

- 정의/개념: 독립된 인증 요소 둘 이상을 검증하는 **MFA**
- 배경/필요성: 비밀번호만으로는 **자격증명 유출•재사용** 방어 불가

#### 한줄 요약

- 비밀번호 유출 시에도 소유/생체 기반 2차 인증 요소를 추가 집행하여 계정 접근을 차단함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지식 요소(Knowledge Factor)**: 비밀번호, PIN, 패스프레이즈 등 사용자가 머릿속으로 알고 있는 정보.
- **소유 요소(Possession Factor)**: 보안키, OTP 토큰, 스마트폰 앱 등 사용자가 물리적으로 소유한 물건.
- **생체 요소(Inherence Factor)**: 지문, 안면, 홍채 등 사용자의 고유한 신체/행동적 특성.
- **피싱 저항성(Phishing Resistance)**: 공격자의 중간자(MitM) 역프록시 피싱 사이트나 릴레이 공격에도 인증정보가 우회 유출되지 않는 특성.

</details>

- **지식 요소**, **소유 요소**, **생체 요소** 간 카테고리 독립성 확보.
- FIDO2/WebAuthn 등 도메인 바인딩 기술을 적용한 **피싱 저항성(Phishing Resistance)** 확보.
- 인증기 최초 등록, 분실 복구 및 기기 변경 수명주기의 동등 보증 수준 관리.

#### 한줄 요약

- 요소 간 독립성 및 FIDO2 기반 피싱 저항성을 확보하고 계정 복구 절차를 엄격히 통제함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인증기 등록(Authenticator Registration)**: 사용자의 신원을 확정한 후 FIDO 공개키나 OTP 시드(Seed)를 기기에 안착시키는 바인딩 과정.
- **비상 계정(Break-glass Account)**: MFA 기기 분실 또는 백엔드 인증 서버 장애 시 긴급 접근을 보장하는 특수 복구 계정.

</details>

```text
다중 인증 구조
├─ 위험•보증 정책: 행위별 요소•강도 정의
├─ 인증기 등록: 사용자•기기 결합
├─ MFA 검증기: 독립 요소 응답 확인
├─ 인증 세션: 결과•유효 시간 유지
└─ 복구•감사: 분실 복구•예외 추적
```

| 구성요소 | 책임 |
|:---|:---|
| 위험•보증 정책 | AAL(Authenticator Assurance Level) 레벨별 필요 인증 요소 정의 |
| 인증기 등록 | 신원 검증 후 공개키/시드를 기기에 맵핑하는 **인증기 등록** 집행 |
| MFA 검증기 | 클라이언트가 제출한 2차 인증 증명(Challenge-Response) 검증 |
| 인증 세션 | 성공된 인증 상태의 유효 기한(TTL) 및 세션 토큰 부여 |
| 복구•감사 | 분실 처리, **비상 계정(Break-glass Account)** 사용 이력 감사 로그 생성 |

#### 한줄 요약

- AAL 정책 정의, 인증기 기기 등록, Challenge-Response 응답 검증 및 비상 계정 관리를 집행함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **재인증(Re-authentication)**: 비밀번호 변경, 자금이체 등 고위험 연산 실행 전 2차 요소를 다시 재확인하는 통제.
- **위험•요구 요소 선정**: 요청 리소스의 중요도에 맞춘 인증 인자 레벨 확정 단계.
- **일회성 도전값 생성**: Nonce 난수를 생성하여 클라이언트에 전송하는 단계.
- **독립 요소 증명 생성**: 보안키/생체센서 기반 서명 응답을 생성하는 단계.
- **등록 결속•응답 검증**: 서버 등록 데이터와 도전값 서명을 비교 검증하는 단계.
- **세션 발급•감사 기록**: 토큰 발급 및 접속 로그 기록 단계.

</details>

```text
인증 요청
    │
    ▼
1. 위험•요구 요소 선정
    │
    ▼
2. 일회성 도전값 생성
    │
    ▼
3. 독립 요소 증명 생성
    │
    ▼
4. 등록 결속•응답 검증
    │
    ├─ 실패 ── 접근 거부•감사
    │
    └─ 성공 ── 5. 세션 발급•감사 기록
                         │
                         ▼
                   고위험 행위 요청
                         │
                         └─ 재인증 후 허용
```

### 동작 원리

1. **위험•요구 요소 선정**: 요청 업무 위험도(AAL1~3) 기반 인증 요소 조합 확정.
2. **일회성 도전값 생성**: Replay 공격 방지용 난수 Challenge 생성.
3. **독립 요소 증명 생성**: 보안키/전자서명 기반 도전값 서명 생성.
4. **등록 결속•응답 검증**: 등록된 공개키로 서명 검증 및 도메인 바인딩 대조.
5. **세션 발급•감사 기록**: 인증 성공 세션 발급 및 실패 로그 저장.

#### 한줄 요약

- 요구 요소 선정, 일회성 도전값 생성, 독립 서명 증명, 서버 검증 및 세션 발급으로 구동됨.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일회용 비밀번호(One-Time Password, OTP)**: 시간(TOTP) 또는 카운터(HOTP) 기반으로 매번 변경되는 난수 코드.
- **푸시 승인(Push Approval)**: 모바일 앱 팝업을 통해 호출 요청을 승인하는 방식.
- **FIDO(Fast Identity Online)**: 공개키 암호학 기반 비패스워드/피싱 저항성 표준 인증 규격.
- **SMS/OTP**: 이동통신사 문자메시지로 OTP를 전달하는 기법.
- **SIM 스와핑(SIM Swapping)**: 공격자가 피해자의 폰 번호를 악성 SIM 카드로 유무선 이전시켜 SMS OTP를 탈취하는 공격.

</details>

| MFA 인증 유형 | SMS/OTP | 푸시 승인 | FIDO 인증 |
|:---|:---|:---|:---|
| 적용 기준 | 기존 환경 보조 인증 | 모바일 간편 승인 | 중요 계정 피싱 저항 인증 |
| 핵심 특징 | **SMS** 기반 **OTP** 수신 | 앱 팝업 승인버튼 터치 | **FIDO2/WebAuthn** 공개키 서명 |
| 한계 | 피싱 및 **SIM 스와핑** 취약 | MFA Fatigue(승인 피로) 공격 | 하드웨어 보안키/기기 필요 |

#### 한줄 요약

- SMS/OTP의 가용성, 푸시 승인의 편의성, FIDO2/WebAuthn의 피싱 저항성을 비교 선택함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-63B-4**: 디지털 정체성 지침 중 인증 및 자격증명 관리 표준.
- **승인 피로(MFA Fatigue / Push Spam)**: 대량의 푸시 승인 요청을 연속 발송하여 사용자의 실수 승인을 유도하는 공격.
- **번호 일치(Number Matching)**: 푸시 승인 시 웹 화면에 표시된 2자리 숫자를 앱에 직접 입력하게 만들어 승인 피로 공격을 무력화하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SMS 취약성 및 계정 탈취 | **NIST SP 800-63B-4** 지침 준수 및 **FIDO2** 전환 | 중간자 피싱 및 SIM 스와핑 차단 |
| MFA Fatigue 무차별 푸시 공격 | **번호 일치(Number Matching)** 적용 | 오승인 및 푸시 스팸 무력화 |
| 계정 복구 경로 우회 공격 | 본 인증과 동등 수준 신원확인 및 **비상 계정** 감사 | 복구 절차 우회 억제 |

#### 한줄 요약

- NIST SP 800-63B-4 가이드라인을 준수하고, FIDO2 피싱 저항성 인증 및 푸시 번호 일치를 적용함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **동등 보증 강도(Equivalent Assurance Level)**: 계정 등록, 기기 변경 및 복구 절차의 보안 수준을 메인 MFA 인증과 동일 레벨로 통제하는 원칙.

</details>

- **동등 보증 강도** 원칙에 입각하여 본 인증은 **FIDO2**, 고위험 요청은 **재인증**, 복구 절차는 동일 수준 강도로 보호.

#### 한줄 요약

- 본 인증은 **FIDO2**, 고위험 행위는 **재인증** 적용
