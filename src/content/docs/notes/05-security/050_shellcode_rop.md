## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **쉘코드 (Shellcode)**: 해커가 버퍼 오버플로우로 메모리를 뚫은 뒤, 내 서버에 셸(CMD 명령창)을 띄우려고 밀어넣는 팩트 악성 기계어 조각이다.
- **ROP (Return-Oriented Programming)**: DEP(데이터 실행 방지) 때문에 쉘코드 실행이 막히자, 이미 서버 메모리에 합법적으로 올라와 있는 정상 코드 조각(가젯)들을 프랑켄슈타인처럼 기워 붙여서 팩트 해킹하는 지독한 우회 기법이다.

</details>

- 정의: 쉘코드는 취약점 공격 성공 시 대상 시스템에 삽입하여 실행하는 기계어 조각이며, ROP는 바이너리 내부의 기존 명령 조각(Gadget)들을 연결하여 임의 코드를 실행하는 팩트 제어 흐름 탈취 공격이다.
- 배경: 메모리 데이터 영역의 실행을 막는 DEP/NX 방패만으로는, 해커 코드가 아닌 '이미 존재하는 정상 코드' 조각을 교묘하게 재사용하는 ROP 우회 공격을 팩트로 차단할 수 없기 때문이다.

#### 한줄 요약

- 해커가 총(쉘코드)을 못 들고 들어오게(DEP) 막았더니, 내부 부품(가젯)을 주워다 조립해서(ROP) 팩트로 쏴버리는 공격이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **CFI (제어 흐름 무결성, Control-Flow Integrity)**: 프로그램이 실행될 때 "이 함수에서 저 함수로 점프 뛰는 게 원래 설계도에 있던 정상적인 흐름 맞아?" 하고 실시간 팩트 감시하는 내비게이션 검사기다.
- **그림자 스택 (Shadow Stack)**: 스택에 돌아갈 주소(RET)를 저장할 때, 해커가 못 건드리는 하드웨어 비밀 공간(그림자)에 똑같이 하나 더 팩트 복사해두고 나중에 변조 여부를 비교하는 이중 장부다.

</details>

- **팩트 제어 데이터 오염**: 버퍼 오버플로우로 함수 반환 주소(RET)나 함수 포인터를 오염시켜, 해커가 원하는 쉘코드나 ROP 가젯으로 실행 흐름을 팩트 탈취한다.
- **팩트 NX와 ASLR 한계**: NX/DEP로 데이터 창고에서 쉘코드를 팩트 차단해도, ASLR(주소 섞기) 방어막만 뚫리면 가젯 주소를 찾아내 ROP로 팩트 우회 공격이 들어온다.
- **팩트 CFI 및 그림자 스택 방어**: 기존 코드를 꿰어 맞추는 ROP를 잡기 위해, CFI로 비정상 점프(JMP/CALL)를 막고 하드웨어 그림자 스택으로 RET 변조를 최종 팩트 차단한다.

#### 한줄 요약

- 외부 악성 코드는 NX로 막고, 내부 코드 조립(ROP)은 CFI와 그림자 스택으로 팩트 박살 내는 게 특징이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **가젯 (Gadget)**: `pop; ret;` 처럼 기존 정상 라이브러리(libc 등) 안에 굴러다니는 2~3줄짜리 팩트 기계어 레고 블록이다. 해커가 이걸 ret 명령어로 이어 붙여서 악성 로직을 완성한다.

</details>

```text
[ 쉘코드 및 ROP 팩트 방어 아키텍처 ]

[ 1. 메모리 안전 (경계 검사) ] ── ("입력값 길이 팩트로 검사해서 오버플로우 원천 차단함")
      │
      ▼
[ 2. NX (실행 불가 비트) ] ── ("해커가 밀어넣은 쉘코드는 데이터 영역이라 팩트 실행 금지됨")
      │
      ▼
[ 3. ASLR (주소 난수화) ] ── ("가젯(레고 블록) 찾아서 ROP 하려는데, 메모리 주소를 매번 팩트로 섞어버림")
      │
      ▼
[ 4. CFI (제어 흐름 무결성) ] ── ("주소 유출로 가젯 찾았어도, 설계도에 없는 비정상 JMP/CALL 흐름이면 팩트로 컷!")
      │
      ▼
[ 5. 그림자 스택 (Shadow Stack) ] ── ("마지막 반환 시, 숨겨둔 이중 장부 사본이랑 주소 대조해서 변조됐으면 팩트 킬!")
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **메모리 안전 코딩** | 버퍼 경계를 넘어서 제어 데이터(RET)를 **오염시키는 1차 원인을 팩트로 차단함** | Source |
| **NX / DEP** | 데이터 영역에 삽입된 **외부 악성 쉘코드의 실행을 CPU 레벨에서 팩트로 거부함** | NX |
| **ASLR (주소 난수화)** | ROP 공격의 핵심인 **가젯(Gadget)의 메모리 주소 예측을 팩트로 무작위 방해함** | ASLR |
| **CFI (흐름 무결성)** | 설계도에 없는 비정상적인 **가젯 간 점프(JMP/CALL) 연결 흐름을 팩트로 컷함** | CFI |
| **그림자 스택** | 해커가 변조한 반환 주소를 **안전한 하드웨어 사본(그림자)과 팩트 대조해 적발함** | Shadow |

#### 한줄 요약

- 데이터는 못 돌리게(NX), 주소는 못 찾게(ASLR), 점프는 이상하게 못 뛰게(CFI), 복귀 주소는 장부 대조(그림자 스택) 팩트 검사한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ ROP 익스플로잇 및 다층 팩트 방어 흐름 ]

┌──────────────────────────────┐
│ 1. [제어 데이터 팩트 오염 (Overflow 발생)]
│ ("버퍼 오버플로우 취약점을 이용해 스택의 반환 주소(RET)를 해커가 무단 팩트 조작함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [NX 판정 (쉘코드 주입 팩트 1차 차단)]
│ ("해커 코드를 직접 실행하려 했으나, 데이터 창고 실행 불가(NX) 속성에 팩트로 막힘")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [ROP 가젯 팩트 체이닝 (NX 우회 시도)]
│ ("NX 뚫으려고 서버에 이미 있는 정상 라이브러리의 가젯 조각(pop; ret;)들을 팩트로 엮음")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [방어 1: ASLR 팩트 무작위화 차단]
│ ("가젯 주소를 찾으려 했으나, 메모리가 섞여 있어서 팩트 못 찾고 크래시 남!")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 5. [방어 2: CFI 및 그림자 스택 팩트 판정 (최종)]
    │ ("주소 뚫고 점프 뛰었지만, 흐름이 이상하고 사본과 달라서 CPU가 프로세스 팩트 킬!")
    └──────────────────────────────┘
```

### 동작 원리

1. 제어 데이터 오염: 오버플로우로 인해 정상적인 반환 주소(RET)가 해커의 페이로드로 덮어씌워짐.
2. NX 판정: 해당 영역이 데이터 스택/힙일 경우 쉘코드(외부 기계어) 직접 실행을 팩트 차단함.
3. 분기/반환 대상 조작: 해커가 NX를 우회하기 위해 정상 라이브러리 내부의 ROP 가젯으로 점프 주소를 조작함.
4. ASLR 무작위화: 메모리 주소를 난수화하여 해커가 원하는 ROP 가젯 주소를 팩트로 찾지 못하게 함.
5. CFI/그림자 스택 판정: 주소 유출(Leak)로 가젯을 찾았더라도, 하드웨어 그림자 스택 대조 및 CFG 검증에 팩트 불일치하여 강제 종료됨.

#### 한줄 요약

- 오버플로우 터지면 $\to$ NX가 쉘코드를 막고 $\to$ ASLR이 가젯 찾기를 방해하고 $\to$ 그림자 스택이 ROP 변조를 팩트로 쏴 죽인다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 제어 탈취 공격 유형 | **쉘코드 (Shellcode)** | **ROP (Return-Oriented Programming)** |
|:---|:---|:---|
| 팩트 폭행 비유 | **해커가 외부에서 권총(코드)을 몰래 들고 들어와서 팩트 쏘기** | **방어벽 땜에 총 못 들고 오니, 내부 부품(가젯) 조립해서 총 팩트로 만들기** |
| 핵심 공격 방식 | 버퍼 오버플로우로 밀어 넣은 **자신의 외부 기계어 코드를 직접 팩트 실행함** | 메모리에 이미 올라와 있는 **정상 코드 조각(가젯)을 `ret` 명령어로 팩트 연결함** |
| 주요 방어 기법 | 데이터 영역의 실행 권한을 박탈하는 **NX/DEP만 켜놔도 매우 쉽게 팩트 원천 차단됨** | 기존 정상 코드를 돌려 쓰므로 NX가 안 먹혀서, **ASLR 주소 섞기나 CFI로 팩트 방어해야 함** |
| 한계 및 문제점 | NX 비트가 켜진 현대 운영체제 환경에서는 **단독으로 절대 팩트 구동되지 않음(무쓸모)** | 메모리 주소가 한 번이라도 유출(Memory Leak)되면 가젯 위치를 들켜서 **ASLR 방패가 팩트 박살남** |

#### 한줄 요약

- 외부 주입 코드를 직접 돌리는 게 **쉘코드**고, 내부 코드를 재활용해서 교묘하게 우회하는 게 **ROP** 팩트 공격이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Intel CET (인텔 제어 흐름 강제 기술)**: 인텔 11세대 CPU부터 아예 하드웨어(칩셋) 안에 CFI와 그림자 스택 기능을 팩트로 구워버려서, 소프트웨어 방어보다 훨씬 빠르고 강력하게 ROP를 막는 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| NX 방어벽 하나만 믿고 배째다가 **ROP 연계 공격에 팩트로 서버 장악당함** | DEP/NX는 외부 쉘코드만 막을 뿐, 내부 정상 코드를 재사용하는 ROP를 못 막는다는 걸 팩트 간과함 | NX뿐만 아니라 **ASLR(주소 무작위화)** 및 **PIE**를 컴파일/OS 단에 동시 적용하여 가젯 팩트 추정 방해 | 쉘코드는 NX로 막고, ROP는 ASLR로 막는 메모리 방패 팩트 다층화 확보 |
| 메모리 주소가 한 줄 유출(Leak)되어 **ASLR이 뚫리고 ROP에 팩트 털림** | ASLR은 주소를 섞을 뿐, 버그로 인해 베이스 주소값이 한 번 유출되면 모든 가젯 위치가 팩트 노출됨 | **Intel CET(CFI/Shadow Stack)** 등 하드웨어 지원 제어 흐름 강제 기술 최신 팩트 도입 | 주소가 유출되어도 비정상적인 분기/반환 흐름을 하드웨어에서 팩트로 즉각 컷 |
| ROP 방어한다고 S/W 검사 돌리다가 **메인 시스템 성능이 팩트로 반토막 남** | 소프트웨어 레벨에서 모든 JMP/CALL의 무결성(CFI)을 검사하느라 처리 오버헤드가 팩트로 폭증함 | OS 커널과 CPU 하드웨어 단의 **Shadow Stack (그림자 스택)** 팩트 활성화 | 시스템 성능 저하(오버헤드) 낭비 없이, 실시간 반환 주소 무결성 팩트 보장 |

#### 한줄 요약

- NX와 ASLR만 믿지 말고, 요즘 최신 CPU가 지원하는 하드웨어 방어(Intel CET, 그림자 스택)까지 팩트로 다 켜라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **공격 경로별 팩트 실행 보호**: 쉘코드는 실행 권한(NX)으로, 가젯 수집은 주소 난수화(ASLR)로, 실행 점프는 흐름 무결성(CFI)으로 공격 각 단계를 팩트로 잘라버리는 심층 방어 모델.

</details>

- 쉘코드 및 ROP 공격은 메모리 제어 데이터 붕괴에서 기인하므로, 단순 쉘코드 주입은 **NX/DEP**로 팩트 차단하고, 주소 예측은 **ASLR**로 무력화하며, 최종적인 ROP 가젯 재사용 우회는 **CFI**와 하드웨어 기반 **그림자 스택(Shadow Stack)**으로 다층 억제하는 실무 기조를 확립함

#### 한줄 요약

- 단순 주입은 **NX**, 주소 예측은 **ASLR**, 얍삽한 ROP는 **CFI와 그림자 스택**으로 팩트 방어해라.
