## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **쉘코드**: 취약한 프로세스에 주입해 공격 동작을 수행하는 기계어 코드이다.
- **반환 지향 프로그래밍(Return-Oriented Programming, ROP)**: 기존 코드의 짧은 가젯을 연결해 공격 동작을 구성하는 기법이다.

</details>

- 정의/개념: **쉘코드**는 새 코드를 주입하고 **ROP**는 기존 코드를 재사용해 실행 흐름을 탈취한다.
- 배경/필요성: 데이터 영역 실행을 막는 NX만으로는 기존 실행 코드의 재사용을 차단할 수 없다.

#### 한줄 요약

- 쉘코드는 새 기계어를 넣어 실행하고 ROP는 이미 있는 짧은 코드를 이어 실행하므로, 메모리 오류 수정과 실행 흐름 보호가 모두 필요하다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **제어 데이터**: 반환 주소•함수 포인터처럼 다음 실행 위치를 정하는 값이다.
- **실행 불가(No-eXecute, NX)**: 데이터 메모리 페이지의 코드 실행을 금지하는 보호 속성이다.
- **주소 공간 배치 무작위화(Address Space Layout Randomization, ASLR)**: 메모리 영역의 시작 주소를 무작위화하는 보호 기법이다.
- **제어 흐름 무결성(Control-Flow Integrity, CFI)**: 간접 분기와 호출이 허용 대상에만 도달하도록 검증하는 보호 기법이다.
- **그림자 스택**: 별도 보호 영역의 반환 주소 사본과 실제 반환 주소를 대조하는 기법이다.

</details>

- **제어 데이터** 손상은 쉘코드와 ROP가 실행 흐름을 바꾸는 공통 전제이다.
- **NX**는 데이터 실행을, **ASLR**은 주소 예측을 각각 억제한다.
- **CFI**와 **그림자 스택**은 비정상 분기와 변조된 반환을 검증한다.

#### 한줄 요약

- NX는 데이터 영역의 쉘코드 실행을 막지만 기존 코드를 쓰는 ROP는 막지 못하므로, 주소 무작위화와 분기•반환 검사를 겹쳐 적용한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **메모리 안전**: 허용된 객체 경계와 수명 안에서만 메모리를 읽고 쓰는 성질이다.
- **가젯**: ROP가 연결해 사용하는 짧은 기존 명령열이다.

</details>

```text
제어 탈취 다층 방어
├─ 메모리 안전: 경계 밖 쓰기•수명 오류 방지
├─ NX•메모리 권한: 데이터 페이지 실행 금지
├─ ASLR: 코드•라이브러리 주소 무작위화
├─ CFI: 간접 분기•호출 대상 제한
└─ 그림자 스택: 반환 주소 사본 대조
```

| 구성요소 | 책임 |
|:---|:---|
| 메모리 안전 | **메모리 안전**으로 경계 밖 쓰기•수명 종료 접근 방지 |
| NX•메모리 권한 | **NX**로 데이터 페이지 실행 금지 |
| ASLR | **ASLR**로 코드•라이브러리•스택 주소 무작위화 |
| CFI | **CFI**로 허용 대상만 간접 분기•호출 허용 |
| 그림자 스택 | **그림자 스택**의 반환 주소 사본 대조 |

#### 한줄 요약

- 입력 경계를 먼저 지키고, 오류가 남더라도 데이터 실행•주소 예측•비정상 분기•변조된 반환 주소를 차례로 제한한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **코드 주입**: 외부 데이터를 프로세스 메모리에 넣어 명령어로 실행하는 공격이다.
- **흐름 검증**: 간접 분기•호출•반환이 허용 대상과 보존된 반환 주소로만 이동하는지 확인하는 통제이다.
- **손상된 제어 데이터**: 공격자가 바꾼 반환 주소•함수 포인터가 다음 실행 위치를 지정하는 상태이다.
- **실행 페이지 속성 확인**: 다음 명령 주소가 속한 메모리 페이지의 실행 권한을 조회하는 단계이다.
- **NX 판정**: 조회한 페이지가 실행 가능한지를 NX 정책으로 결정하는 단계이다.
- **분기•반환 대상 확인**: 간접 분기와 반환 주소가 허용 목록에 속하는지 검사하는 단계이다.
- **CFI•그림자 스택 판정**: 허용 흐름과 보호된 반환 주소 사본의 일치 여부를 최종 결정하는 단계이다.

</details>

```text
경계 초과 입력
      |
      v
1. 손상된 제어 데이터
      |
      v
2. 실행 페이지 속성 확인
      |
      v
3. NX 판정
      |
      +-- 실행 불가 -- 쉘코드 차단
      |
      +-- 실행 가능 -- 4. 분기•반환 대상 확인
                              |
                              v
                    5. CFI•그림자 스택 판정
                              |
                  +-----------+-----------+
                  |                       |
             불일치 차단             허용 흐름 실행
```

### 동작 원리

1. **손상된 제어 데이터**: 변조된 반환 주소•함수 포인터가 실행 위치를 제공하는 손상된 제어 데이터 상태가 된다.
2. **실행 페이지 속성 확인**: 다음 명령 주소가 속한 페이지를 찾아 실행 페이지 속성 확인을 수행한다.
3. **NX 판정**: 데이터 페이지인지 검사하는 NX 판정으로 쉘코드 실행을 거부한다.
4. **분기•반환 대상 확인**: 가젯의 간접 분기와 반환 주소에 대해 분기•반환 대상 확인을 수행한다.
5. **CFI•그림자 스택 판정**: 허용 경로•반환 주소 사본의 불일치를 CFI•그림자 스택 판정으로 탐지한다.

#### 한줄 요약

- **코드 주입**은 NX가, 기존 **가젯**으로 이동하는 ROP는 **흐름 검증**이 차단한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **제어 탈취 방어 선택 기준**: 외부 코드 주입에는 NX, 기존 코드 재사용에는 CFI•그림자 스택을 적용하는 판단 기준이다.

</details>

| 제어 탈취 유형 | 쉘코드 주입 | ROP |
|:---|:---|:---|
| 적용 기준 | 데이터 페이지 실행 가능 | NX 환경의 제어 흐름 손상 |
| 핵심 특징 | **쉘코드** 주입•실행 | **ROP**의 기존 가젯 연결•재사용 |
| 한계 | 악성 명령 직접 실행 | 정상 코드 기반 탐지•차단 곤란 |

#### 한줄 요약

- **제어 탈취 방어 선택 기준**에 따라 새 코드를 넣는 쉘코드는 실행 권한으로, 기존 코드를 잇는 ROP는 제어 흐름으로 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **MITRE CWE-787**: 경계 밖 쓰기로 제어 데이터가 손상되는 약점을 정의한 공통 약점 분류이다.
- **인텔 제어 흐름 강제 기술(Control-flow Enforcement Technology, Intel CET)**: 간접 분기 추적과 하드웨어 그림자 스택으로 ROP를 억제하는 기술이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 경계 밖 쓰기로 제어 데이터가 손상되면 실행 탈취 | **MITRE CWE-787** 기준으로 원인 제거 | 공격 전제인 메모리 결함 차단 |
| ROP가 허용되지 않은 분기•반환을 연결 | **Intel CET**•**CFI** 적용 | 가젯 연결과 반환 변조 억제 |
| 빌드별 보호 옵션 누락으로 코드 주입•주소 예측 가능 | 산출물 검사로 **NX**•**ASLR** 적용 확인 | 코드 주입과 주소 예측 제한 |

#### 한줄 요약

- 배포된 서버 바이너리에 NX•ASLR•CFI가 실제 적용됐는지 확인해 주입 코드 실행과 ROP 가젯 연결을 어렵게 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **공격 경로별 실행 보호**: 코드 주입•가젯 재사용•주소 예측의 서로 다른 경로에 각각 NX•CFI와 그림자 스택•ASLR을 대응하는 원칙이다.

</details>

- **공격 경로별 실행 보호**에 따라 코드 주입은 **NX**, 가젯 재사용은 **CFI**•**그림자 스택**, 주소 예측은 **ASLR**로 억제한다.

#### 한줄 요약

- 메모리 결함을 먼저 고치고 NX•CFI•그림자 스택을 겹쳐 적용해야 새 코드 주입과 기존 코드 재사용 경로를 함께 줄일 수 있다.
