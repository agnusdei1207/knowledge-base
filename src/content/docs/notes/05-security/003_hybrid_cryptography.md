## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이브리드 암호(Hybrid Cryptography)**: 비대칭키(공개키) 암호의 '안전한 키 분배' 능력과 대칭키 암호의 '초고속 대용량 처리' 능력을 유기적으로 결합하여, 성능과 보안성을 동시에 충족하는 현대 실용 암호체계 (TLS 1.3, PGP, HPKE의 기반).
- **KEM(Key Encapsulation Mechanism) & DEM(Data Encapsulation Mechanism)**: 비대칭키로 대칭 세션키를 안전하게 캡슐화하여 교환하는 KEM 계층과, 합의된 세션키를 바탕으로 대용량 페이로드를 고속 대칭 암호화(AEAD)하는 DEM 계층의 분업 구조.

</details>

- 정의/개념: 비대칭 암호 알고리즘(ECDHE/ML-KEM)을 사용하여 안전하게 **공유 비밀(Shared Secret)** 을 합의(KEM)하고, **KDF(키 유도 함수)** 를 통해 도출된 대칭키로 대용량 본문을 **AEAD(AES-GCM/ChaCha20)** 방식으로 암호화(DEM)하는 **2계층 복합 암호 프레임워크**
- 배경/필요성: 비대칭 암호 단독 사용 시 수백 메가바이트~기가바이트 단위의 미디어/파일 데이터 암호화에서 발생하는 극심한 CPU 연산 지연과 버퍼 오버헤드 병목을 해소할 요구

#### 한줄 요약
- 비대칭키로 세션키를 안전하게 교환(KEM)하고, 대칭키로 본문 데이터를 초고속 암호화(DEM)한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **키 유도 함수(Key Derivation Function, HKDF / RFC 5869)**: KEM으로 획득한 원시 공유 비밀(Shared Secret)로부터 암호학적 엔트로피를 추출(Extract)하고 확장(Expand)하여 송수신 방향별 독립 암호키와 초기화 벡터를 도출하는 함수.
- **도메인 분리(Domain Separation)**: 단일 마스터 키에서 파생된 키들이 서로 다른 프로토콜 문맥이나 방향(Client-to-Server vs Server-to-Client)에서 혼용되지 않도록 컨텍스트 문자열 라벨을 주입하는 안전 설계.

</details>

- **연산 복잡도 최적화 (KEM-DEM Separation)**: 무거운 수학적 비대칭 연산은 핸드셰이크 시점 1회로 국한하고, 본문 전송은 하드웨어 가속(AES-NI) 대칭키로 전담
- **엄격한 다계층 키 스케줄링**: HKDF 기반으로 클라이언트 암호키, 서버 암호키, 인증용 MAC 키를 물리적/논리적으로 완전 분리
- **RFC 9180 HPKE(Hybrid Public Key Encryption) 표준화**: 비대칭 KEM, 키 유도 KDF, 대칭 AEAD를 모듈화하여 암호 알고리즘의 유연한 교체(Crypto Agility) 보장

#### 한줄 요약
- KEM-DEM 분업 최적화, HKDF 기반 방향별 키 분리, RFC 9180 HPKE 모듈 표준화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인증 모듈(Authentication Module)**: 통신 개시 전 상대방의 공개키가 정당한 엔티티의 것인지 X.509 PKI 인증서와 전자서명을 통해 검증하는 선행 검증 모듈.

</details>

```text
[ 송신자 (Alice) ]                                                  [ 수신자 (Bob) ]
 ├─ 수신자 공개키 (PKI 인증서 검증 완료)                                ├─ 수신자 개인키 (HSM 내 안전 보관)
 │                                                                     │
 ▼                                                                     │
[ 1. KEM 계층 (Key Encapsulation) ] ── (세션키 캡슐화 데이터 전송) ──▶ [ KEM 캡슐 해제 계층 ]
 └─ 공유 비밀(Shared Secret) 생성                                      └─ 공유 비밀(Shared Secret) 복원
           │                                                                   │
           ▼                                                                   ▼
[ 2. KDF 계층 (HKDF-Extract/Expand) ]                                 [ KDF 계층 (HKDF-Extract/Expand) ]
 ├─ 송신용 AES-256 키 & Nonce 도출                                     ├─ 수신용 AES-256 키 & Nonce 도출
 └─ 수신용 AES-256 키 & Nonce 도출                                     └─ 송신용 AES-256 키 & Nonce 도출
           │                                                                   ▲
           ▼ (3. 대용량 평문 데이터 AEAD 암호화: DEM 계층)                     │
┌──────────────────────────────────────────────────────────────────────────────┼───────────────────┐
│ [ 대용량 데이터 전송 구간 (Ciphertext + 128bit Auth Tag) ] ──────────────────┘                   │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: KEM 계층에서 비대칭 암호화로 공유 비밀을 교환하고, KDF 계층에서 방향별 대칭키를 도출한 후, DEM 계층에서 대용량 데이터를 초고속 AEAD 암호화하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **신원 인증 모듈** | X.509 인증서 서명 검증 및 핸드셰이크 트랜스크립트(Transcript) 무결성 보증 | PKI / TLS Handshake |
| **KEM 모듈** | 임시 키 교환(ECDHE) 또는 비대칭 키 캡슐화(ML-KEM)를 통해 공유 비밀 수립 | RFC 9180 KEM |
| **KDF 모듈 (HKDF)** | 공유 비밀과 세션 솔트(Salt)를 결합하여 방향별 대칭키(Client/Server Write Key) 도출 | RFC 5869 HKDF |
| **DEM 모듈 (AEAD)**| 도출된 대칭키로 기가바이트급 페이로드의 기밀성 및 128비트 무결성 태그 생성 | AES-GCM / ChaCha20 |

#### 한줄 요약
- 신원 인증 모듈, KEM 키 캡슐화, KDF 키 도출기, DEM AEAD 데이터 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **핸드셰이크 트랜스크립트 바인딩(Transcript Binding)**: 암호 스위트 협상 과정에서 공격자가 약한 알고리즘으로 조작(다운그레이드)하는 것을 방지하기 위해, 핸드셰이크 중 오간 모든 제어 메시지의 해시값을 최종 인증서 서명에 결합하는 기법.

</details>

```text
1. 클라이언트와 서버가 지원 가능한 암호 스위트(Cipher Suites) 목록 교환 및 X.509 인증서 상호 검증
            │
            ▼
2. [KEM 단계] ECDHE 임시 키 쌍 교환(또는 PQC KEM)을 통해 중간자 도청 불가능한 마스터 공유 비밀 생성
            │
            ▼
3. [KDF 단계] HKDF 엔진을 가동하여 마스터 비밀로부터 '클라이언트 송신키'와 '서버 송신키'를 독립 도출
            │
            ▼
4. [DEM 단계] 애플리케이션의 대용량 스트리밍 데이터를 16KB 블록 단위로 분할하여 AES-GCM 고속 암호화
            │
            ▼
5. 수신단이 AEAD 인증 태그를 사전 검증한 후 라인 레이트 속도로 평문 복호화 완료
```

**동작 원리**

1. **상호 인증 및 협상**: 클라이언트와 서버가 TLS 1.3 파라미터를 교환하고 세션 무결성 고정
2. **비대칭 키 캡슐화**: 1회용 임시 키 쌍(ECDHE)을 활용하여 순방향 비밀성(PFS)이 보장된 비밀값 합의
3. **도메인 분리 키 도출**: 송신 방향과 수신 방향에 서로 다른 256비트 대칭키와 96비트 IV 부여
4. **대칭 블록 암호화**: 비대칭 연산 종료 후 전용 대칭키 엔진이 수십 Gbps 속도로 페이로드 암호화
5. **무결성 일체형 검증**: 전송된 패킷마다 128비트 인증 태그를 대조하여 1비트의 변조도 실시간 차단

#### 한줄 요약
- 파라미터 협상, KEM 공유 비밀 생성, HKDF 방향별 키 도출, DEM 대칭 암호화, AEAD 태그 검증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하이브리드 키 설정 방식 진화**: 정적 RSA 키 전송, 임시 타원곡선 ECDHE, 양자내성 PQC-KEM 하이브리드의 비교.

</details>

| 비교 항목 | 정적 RSA 키 전송 (Legacy) | ECDHE 기반 하이브리드 (Current) | PQC KEM 결합 하이브리드 (Future) |
|:---|:---|:---|:---|
| **키 교환 메커니즘** | **송신자가 대칭키를 RSA 공개키로 암호화**| **임시 타원곡선 키 교환 (ECDHE)** | **고전 ECDHE + 양자내성 ML-KEM 결합** |
| **순방향 비밀성 (PFS)**| **미지원 (서버 개인키 유출 시 전면 해독)**| **완벽 지원 (세션 종료 시 임시 키 폐기)**| **완벽 지원 (양자 공격 환경에서도 보장)**|
| **양자 공격 저항성** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **영구적 안전 (NIST FIPS 203 표준)** |
| **연산 오버헤드** | RSA 거듭제곱 연산으로 다소 무거움 | **극도로 가볍고 빠름 (X25519 최적화)** | 격자 연산 추가로 키 크기 다소 증가 |
| **주요 적용 표준** | TLS 1.0 ~ 1.2 (폐기 권고) | **표준 TLS 1.3, SSHv2, IPsec IKEv2** | **X25519+Kyber768 (Chrome, Cloudflare)**|

#### 한줄 요약
- RSA는 PFS 미지원으로 폐기되었으며, 현재는 ECDHE가 표준이고, 미래 양자 방어를 위해 PQC 하이브리드가 채택된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **암호 다운그레이드 공격(Cipher Downgrade Attack)**: 중간자 공격자(MITM)가 클라이언트와 서버 간의 초기 협상 패킷을 변조하여, 양단이 지원 가능한 최신 암호 스위트(TLS 1.3) 대신 취약한 레거시 암호(TLS 1.0/DES)를 강제 선택하게 만드는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 네트워크 중간자가 암호 협상 패킷을 변조하여 취약한 구형 알고리즘으로 강제 유도 | **핸드셰이크 전체 메시지를 해싱하는 트랜스크립트 인증(Finished Verify_Data)** 강제 | 암호 스위트 위변조 탐지 시 연결 즉시 차단 및 다운그레이드 방어 |
| KDF 키 도출 시 컨텍스트 분리 부재로 인한 **송수신 양방향 동일 키 재사용 충돌** | **RFC 9180 HPKE 표준 준수 및 Label/Info 매개변수를 통한 도메인 분리** 적용 | 송수신 간 키스트림 충돌 방지 및 암호학적 독립성 100% 확보 |
| 현재 수집된 하이브리드 암호문이 미래 양자컴퓨터에 의해 일괄 해독되는 SNDL 위협 | **고전 X25519와 양자내성 ML-KEM을 이중 결합한 하이브리드 KEM** 조기 적용 | 고전 알고리즘 호환성을 유지하면서 미래 양자 해독 위협 원천 차단 |

#### 한줄 요약
- 트랜스크립트 서명으로 다운그레이드를 방어하고, HPKE 도메인 분리로 키 충돌을 막으며, PQC KEM으로 양자 위협을 차단한다.

## Ⅶ. 결론

- 대용량 초고속 인터넷 통신과 엔드포인트 보안을 실현하는 실질적 표준인 **하이브리드 암호 아키텍처**는 모든 최신 보안 프로토콜(TLS 1.3, WireGuard, QUIC)의 핵심 뼈대이며, 실무 구현 시 **KEM과 DEM의 명확한 역할 분리**, **HKDF 기반 도메인 분리 키 스케줄링**, **PQC 하이브리드 KEM 전환을 통한 암호 민첩성(Crypto Agility) 확보**를 결합하여 미래 지향적 암호 보안 체계를 완성

#### 한줄 요약
- 비대칭 KEM 키 교환과 대칭 DEM 고속 암호화 및 PQC 하이브리드 전환을 결합하여 고효율 보안 통신을 실현한다.
