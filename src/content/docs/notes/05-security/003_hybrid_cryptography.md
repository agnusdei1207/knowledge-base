## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Hybrid Cryptography (하이브리드 암호)**: 비대칭키의 안전한 키 교환과 대칭키의 고속 대용량 암호화를 결합한 현대 실용 암호체계.
- **KEM & DEM (RFC 9180 HPKE)**: 비대칭키로 세션키를 안전하게 교환하는 KEM 계층과 대칭키로 페이로드를 암호화하는 DEM 계층.

</details>

- 정의/개념: **KEM**·KDF·**DEM**을 결합한 **하이브리드 암호** 방식
- 배경/필요성: 공개키(비대칭) 암호는 안전한 키 교환과 전자서명을 제공하지만 대용량 데이터 암복호화 시 극심한 CPU 연산 오버헤드와 지연을 유발하고, 대칭키 암호는 초고속 암호화가 가능하지만 통신 상대와의 사전 키 배송 문제(Key Distribution Problem)를 스스로 해결하지 못하는 각각의 명확한 공학적 한계를 가짐에 따라, 비대칭 암호의 키 캡슐화(KEM)를 통해 세션키를 안전하게 합의하고 대칭 암호의 데이터 캡슐화(DEM: AEAD)를 통해 대용량 본문 트래픽을 고속 전송하는 하이브리드 암호(Hybrid Cryptography / RFC 9180 HPKE) 구조를 도입하여 키 배송의 보안성과 대용량 데이터 암복호화의 초고속 성능을 동시에 달성, TLS 1.3/IPsec/SSH 등 현대 인터넷 보안 통신의 실용적 구현을 달성할 필요

#### 한줄 요약
- 비대칭 KEM 키 교환과 대칭 DEM 고속 암호화를 결합하여 성능과 보안성을 동시에 충족한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **HKDF (HMAC-based Key Derivation Function, RFC 5869)**: KEM에서 교환된 공유 비밀(Shared Secret)로부터 암호학적으로 독립된 방향별 대칭키를 유도하는 표준 키 유도 함수.
- **Domain Separation (도메인 분리)**: HKDF의 info/label 입력에 용도·방향 문자열을 넣어 같은 공유 비밀에서 파생한 키가 용도마다 다른 값이 되게 하는 기법으로, 한 용도의 키가 드러나도 다른 용도의 키로 번지지 않게 함.

</details>

- 비대칭 **KEM**과 대칭 **DEM**의 역할 분리
- HKDF **도메인 분리**로 방향·용도별 키 도출
- 임시 ECDHE 사용 시 순방향 비밀성 제공

#### 한줄 요약
- 두 계층으로 쪼갠 대가로 KEM과 DEM을 잇는 이음매가 새 공격면이 되므로, HKDF 도메인 분리와 트랜스크립트 결속이 필수 부품으로 따라붙는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Client/Server Write Key**: 단일 공유 비밀로부터 HKDF를 통해 클라이언트 송신용과 서버 송신용으로 각각 독립 유도된 256비트 대칭키.

</details>

```text
[하이브리드 암호 체계]
  │
  ├─ [인증 평면]
  │    └─ 인증 모듈 (인증서·서명)
  │
  ├─ [키 교환 평면: KEM]
  │    └─ 비대칭 KEM (공유 비밀 합의)
  │
  ├─ [키 유도 평면: KDF]
  │    └─ HKDF (방향별 대칭키 도출)
  │
  └─ [데이터 평면: DEM]
       └─ 대칭 DEM (AEAD 고속 암호화)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| Authentication Module | 인증서·트랜스크립트 검증 |
| KEM Module | 공유 비밀 캡슐화·합의 |
| KDF Module | **HKDF** 기반 **Client/Server Write Key** 도출 |
| DEM Module | AEAD 본문 암호화·인증 |

#### 한줄 요약
- KDF 계층은 공유 비밀 하나를 방향·용도별 키로 갈라 놓아, 한쪽 키가 노출돼도 다른 방향의 트래픽까지 번지지 않도록 피해 범위를 계층 안에서 끊는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Transcript Hash Binding**: 암호 협상 과정에서 공격자가 약한 알고리즘으로 다운그레이드하는 것을 막기 위해 모든 제어 메시지의 해시값을 최종 서명에 결합하는 기법.

</details>

```text
하이브리드 암호 스위트 협상, KEM 키 교환, KDF 유도 및 DEM 암호화 파이프라인
        │
   1. [암호 스위트 협상 및 인증]
        │
   2. [KEM 공유 비밀 수립]
        │
   3. [KDF 방향별 키 도출]
        │
   4. [DEM 본문 암호화]
        │
   ▼
   5. [AEAD 검증 및 복호화]
```

- 1. 암호 스위트 협상 및 인증
- 2. KEM 공유 비밀 수립
- 3. KDF 방향별 키 도출
- 4. DEM 본문 암호화
- 5. AEAD 검증 및 복호화

#### 한줄 요약
- 앞의 협상·KEM 구간은 세션당 한 번뿐인 고정 비용이고 뒤의 DEM 구간만 데이터량에 비례하므로, 하이브리드의 성능은 사실상 세션 재사용 여부가 좌우한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **X25519MLKEM768 (하이브리드 키 합의 그룹)**: X25519 공유 비밀과 ML-KEM-768 캡슐화 비밀을 이어 붙여 하나의 KDF 입력으로 삼는 TLS 1.3 키 교환 그룹으로, 둘 중 하나만 깨지지 않으면 세션키가 안전하게 유지됨.

</details>

| 비교 항목 | 정적 RSA 키 전송 (Legacy) | ECDHE 기반 하이브리드 (Current) | PQC KEM 결합 하이브리드 (Future) |
|:---|:---|:---|:---|
| 키 설정 | RSA 키 전송 | ECDHE | **X25519MLKEM768** 결합 |
| 순방향 비밀성 | 미지원 | 임시 키 폐기 시 지원 | 구성과 키 폐기에 좌우 |
| 양자 공격 | Shor 알고리즘에 취약 | Shor 알고리즘에 취약 | PQC KEM 포함 |
| 크기·연산 | RSA 연산 부담 | 작은 키와 빠른 연산 | 캡슐 크기·연산 증가 |
| 주요 적용 | 레거시 TLS | TLS 1.3·SSH·IKEv2 | 전환기 하이브리드 TLS |

#### 한줄 요약
- RSA는 PFS 미지원으로 폐기되었으며, 현재는 ECDHE가 표준이고, 미래 양자 방어를 위해 PQC 하이브리드가 채택된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Cipher Downgrade Attack (다운그레이드 공격)**: 중간자 공격자가 협상 패킷을 변조하여 취약한 레거시 암호 스위트(TLS 1.0/DES)를 강제 선택하게 만드는 공격.
- **STEK (Session Ticket Encryption Key)**: 서버가 세션 재개용 티켓을 암호화하는 대칭키로, 이 키가 노출되면 그 키로 발급된 모든 세션의 재개 비밀이 풀리므로 주기적으로 교체해 노출 피해 창을 교체 주기로 제한함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 협상 변조로 **다운그레이드 공격** | **Transcript Hash Binding** | 협상 무결성 검증 |
| 컨텍스트 누락으로 키 충돌 | HPKE Label 기반 **도메인 분리** | 키 용도 독립성 확보 |
| SNDL 양자 위협 | **X25519MLKEM768** 하이브리드 | 고전·PQC 위험 분산 |
| 세션 티켓 키 노출 | **STEK** 자동 순환 | 노출 시간 범위 제한 |

#### 한줄 요약
- 실무 사고는 KEM이나 AEAD 자체가 아니라 둘을 잇는 협상·유도·재개 이음매에서 나므로, 하이브리드 설계 검토는 계층 각각보다 계층 사이를 본다.

## Ⅶ. 결론

- 공개키 암호의 안전한 키 교환과 대칭키 암호의 초고속 와이어 스피드 처리를 완벽하게 융합하여 인터넷의 모든 보안 통신(HTTPS/SSH/VPN/HPKE)을 실질적으로 가능케 한 현대 네트워크 보안 및 데이터 전송 프로토콜의 가장 핵심적인 표준 아키텍처 모델로 확립되었으며, 양자 도청(SNDL)에 대응하는 고전 ECC와 양자내성 KEM(ML-KEM)의 이중 결합으로 진화하는 가운데, 실무 하이브리드 암호 체계 구축 시에는 공격자의 암호 스위트 다운그레이드를 차단하는 전 핸드셰이크 트랜스크립트 해시(Transcript Hash) 서명 결속, 단일 공유 비밀로부터 송수신 방향별 독립 대칭키를 안전하게 유도하는 HKDF 도메인 분리(Domain Separation), 향후 양자 컴퓨터 공격에 대비한 X25519와 ML-KEM-768 하이브리드 키 캡슐화(X25519Kyber768Draft00) 선제 적용을 결합하여 완벽한 보안 통신 효율성과 영속성을 완성

#### 한줄 요약
- 대용량 통신에 공개키 암호를 직접 쓰는 선택지는 없으므로, 설계 질문은 하이브리드 여부가 아니라 KEM에 무엇(ECDHE 단독인가 ML-KEM 결합인가)을 넣을지로 좁혀진다.
