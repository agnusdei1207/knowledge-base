## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Hybrid Cryptography**: 비대칭키의 안전한 키 교환과 대칭키의 고속 대용량 암호화를 결합한 현대 실용 암호체계.
- **KEM & DEM (RFC 9180 HPKE)**: 비대칭키로 세션키를 안전하게 교환하는 KEM 계층과 대칭키로 페이로드를 암호화하는 DEM 계층.

</details>

- 정의/개념: 비대칭키 KEM으로 공유 비밀을 합의하고 **KDF로 도출된 대칭키를 통해 대용량 본문을 AEAD 방식으로 고속 암호화하는 복합 암호 기술**
- 배경/필요성: 대칭키의 안전한 키 배송 한계와 공개키 암호의 연산 부하로 인한 **대용량 파일 및 실시간 네트워크 스트림의 안전하고 빠른 전송 불가**

#### 한줄 요약
- 비대칭 KEM 키 교환과 대칭 DEM 고속 암호화를 결합하여 성능과 보안성을 동시에 충족한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **HKDF (HMAC-based Key Derivation Function, RFC 5869)**: KEM에서 교환된 공유 비밀(Shared Secret)로부터 암호학적으로 독립된 방향별 대칭키를 유도하는 표준 키 유도 함수.

</details>

- **보안성과 연산 성능의 동시 달성**: 키 교환은 **비대칭키의 수학적 난제로 보호하고 본문은 대칭키로 기가비트 라인레이트 전송**
- **명확한 2계층 분업화(KEM + DEM)**: 키 캡슐화(KEM)와 **데이터 암호화(DEM)가 독립 분리되어 암호 알고리즘 교체 용이**
- **완벽한 순방향 비밀성(PFS) 보장**: 임시 키(ECDHE)를 활용하여 **장기 개인키가 유출되어도 과거 세션 데이터 복호화 불가**

#### 한줄 요약
- 보안/성능 양립, KEM+DEM 2계층 분업화, ECDHE 기반 순방향 비밀성(PFS)을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Client/Server Write Key**: 단일 공유 비밀로부터 HKDF를 통해 클라이언트 송신용과 서버 송신용으로 각각 독립 유도된 256비트 대칭키.

</details>

```text
[하이브리드 암호화 KEM-KDF-DEM 3단계 아키텍처]
|-- Client & Server Authentication (X.509 인증서 상호 서명 검증)
`-- 1. KEM Layer (Key Encapsulation: ECDHE 임시 키 교환 또는 ML-KEM)
    `-- Shared Secret (마스터 공유 비밀값 합의)
`-- 2. KDF Layer (HKDF-Extract / HKDF-Expand)
    |-- Client Write Key (256bit AES-GCM 키 & 96bit IV)
    `-- Server Write Key (256bit AES-GCM 키 & 96bit IV)
`-- 3. DEM Layer (Data Encapsulation: 대용량 페이로드 AEAD 고속 암호화)
    `-- Ciphertext + 128bit Auth Tag (네트워크 라인레이트 전송)
```

선의 의미: KEM 계층에서 비대칭 암호화로 공유 비밀을 교환하고 KDF 계층에서 방향별 대칭키를 도출한 후 DEM 계층에서 대용량 데이터를 초고속 AEAD 암호화하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **신원 인증 모듈** | X.509 인증서 서명 검증 및 **핸드셰이크 트랜스크립트 무결성 보증** | PKI / TLS Handshake |
| **KEM 모듈** | 임시 키 교환(ECDHE) 또는 **비대칭 키 캡슐화(ML-KEM)를 통해 공유 비밀 수립** | RFC 9180 KEM |
| **KDF 모듈 (HKDF)** | 공유 비밀과 세션 솔트를 결합하여 **방향별 대칭키(Client/Server Key) 도출** | RFC 5869 HKDF |
| **DEM 모듈 (AEAD)** | 도출된 대칭키로 **기가바이트급 페이로드의 기밀성 및 128비트 무결성 태그 생성** | AES-GCM / ChaCha20 |

#### 한줄 요약
- 신원 인증 모듈, KEM 키 캡슐화, KDF 키 도출기, DEM AEAD 데이터 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Transcript Hash Binding**: 암호 협상 과정에서 공격자가 약한 알고리즘으로 다운그레이드하는 것을 막기 위해 모든 제어 메시지의 해시값을 최종 서명에 결합하는 기법.

</details>

```text
하이브리드 암호 스위트 협상, KEM 키 교환, KDF 유도 및 DEM 암호화 파이프라인
        │
   1. [암호 스위트 협상] 클라이언트와 서버가 지원 목록을 교환하고 X.509 인증서 상호 검증
        │
   2. [KEM 단계] ECDHE 임시 키 교환을 통해 중간자 도청 불가능한 마스터 공유 비밀 생성
        │
   3. [KDF 단계] HKDF 엔진을 가동하여 마스터 비밀로부터 클라이언트/서버 전용 대칭키 독립 도출
        │
   4. [DEM 단계] 대용량 스트리밍 데이터를 블록 단위로 분할하여 AES-GCM 고속 암호화
        │
   ▼
5. [AEAD 검증 및 복호화] 수신단이 128비트 인증 태그를 사전 검증한 후 라인레이트 속도로 복원
```

#### 한줄 요약
- 파라미터 협상 → KEM 공유 비밀 생성 → HKDF 방향별 키 도출 → DEM 대칭 암호화 → AEAD 태그 검증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 RSA (레거시)** vs **ECDHE (현재 표준)** vs **PQC KEM 결합 (미래 양자내성)**.

</details>

| 비교 항목 | 정적 RSA 키 전송 (Legacy) | ECDHE 기반 하이브리드 (Current) | PQC KEM 결합 하이브리드 (Future) |
|:---|:---|:---|:---|
| **키 교환 메커니즘** | **송신자가 대칭키를 RSA 공개키로 암호화**| **임시 타원곡선 키 교환 (ECDHE)** | **고전 ECDHE + 양자내성 ML-KEM 결합** |
| **순방향 비밀성 (PFS)**| **미지원 (서버 개인키 유출 시 전면 해독)**| **완벽 지원 (세션 종료 시 임시 키 폐기)**| **완벽 지원 (양자 공격 환경에서도 보장)**|
| **양자 공격 저항성** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **영구적 안전 (NIST FIPS 203 표준)** |
| **연산 오버헤드** | RSA 거듭제곱 연산으로 다소 무거움 | **극도로 가볍고 빠름 (X25519 최적화)** | 격자 연산 추가로 키 크기 다소 증가 |
| **주요 적용 표준** | TLS 1.0 ~ 1.2 (폐기 권고) | **표준 TLS 1.3, SSHv2, IPsec IKEv2** | **X25519+Kyber768 (Chrome, Cloudflare)**|

#### 한줄 요약
- RSA는 PFS 미지원으로 폐기되었으며, 현재는 ECDHE가 표준이고, 미래 양자 방어를 위해 PQC 하이브리드가 채택된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Cipher Downgrade Attack**: 중간자 공격자가 협상 패킷을 변조하여 취약한 레거시 암호 스위트(TLS 1.0/DES)를 강제 선택하게 만드는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 중간자가 협상 패킷을 변조하여 취약한 구형 알고리즘으로 강제 유도 | **핸드셰이크 전체 메시지를 해싱하는 `트랜스크립트 인증(Verify_Data)`** 강제 | 암호 스위트 위변조 탐지 시 연결 즉시 차단 및 다운그레이드 방어 |
| KDF 키 도출 시 컨텍스트 분리 부재로 인한 **송수신 키 충돌** | **`RFC 9180 HPKE 표준 준수 및 Label 매개변수를 통한 도메인 분리`** 적용 | 송수신 간 키스트림 충돌 방지 및 암호학적 독립성 확보 |
| 현재 수집된 하이브리드 암호문이 미래 양자컴퓨터에 해독되는 SNDL 위협 | **고전 X25519와 양자내성 ML-KEM을 이중 결합한 `하이브리드 KEM`** 적용 | 고전 호환성을 유지하면서 미래 양자 해독 위협 원천 차단 |
| 세션 재사용(Session Resumption) 시 티켓 키 노출로 인한 PFS 상실 | **세션 티켓 암호화 키(STEK)의 `1시간 주기 자동 순환(Rotation)`** 구성 | 세션 재개 속도를 유지하면서 장기 도청 위협 격리 |

#### 한줄 요약
- 트랜스크립트 서명으로 다운그레이드를 방어하고, HPKE 도메인 분리로 키 충돌을 막으며, PQC KEM으로 양자 위협을 차단한다.

## Ⅶ. 결론

- 대용량 초고속 인터넷 통신과 엔드포인트 보안을 실현하는 실질적 표준인 **하이브리드 암호 아키텍처는 모든 최신 보안 프로토콜(TLS 1.3, WireGuard, QUIC)의 핵심 뼈대**이며, 실무 구현 시 **KEM과 DEM의 명확한 역할 분리, HKDF 기반 도메인 분리 키 스케줄링, PQC 하이브리드 KEM 전환을 통한 암호 민첩성(Crypto Agility) 확보**를 결합하여 미래 지향적 암호 보안 체계 완성

#### 한줄 요약
- 하이브리드 암호는 비대칭 KEM 키 교환과 대칭 DEM 고속 암호화 및 PQC 하이브리드 전환을 결합하여 고효율 보안 통신을 실현하는 표준 아키텍처다.
