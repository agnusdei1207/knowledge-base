## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **하이브리드 암호**: 공개키 암호로 임시 공유 비밀을 설정하고 대칭키 암호로 실제 데이터를 보호하는 결합 방식이다.
- **키 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)**: 공개키로 공유 비밀을 설정하는 방식이다.
- **데이터 캡슐화 메커니즘(Data Encapsulation Mechanism, DEM)**: 공유 비밀에서 얻은 대칭키로 본문을 암호화하는 방식이다.
- **KEM 키 설정**: KEM으로 임시 공유 비밀을 생성•캡슐화•복구하는 키 설정이다.
- **DEM 본문 보호**: 공유 비밀에서 유도한 대칭키로 실제 데이터를 보호하는 처리이다.
- **대용량 처리 한계**: 공개키 연산의 높은 계산 비용 때문에 큰 본문을 직접 암호화하기 어려운 한계이다.

</details>

- 정의/개념: **KEM 키 설정**과 **DEM 본문 보호**를 결합한 **하이브리드 암호**이다.
- 배경/필요성: 공개키 암호의 **대용량 처리 한계** 해소가 필요하다.

#### 한줄 요약

- 공개키 암호는 처음 만난 상대와 열쇠를 정할 때만 쓰고, 이후 큰 짐은 빠른 대칭키 암호로 계속 운반한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **세션키**: 하나의 통신 연결이나 제한된 기간의 데이터 보호에 사용하는 임시 대칭키이다.
- **키 유도 함수(Key Derivation Function, KDF)**: 공유 비밀에서 용도와 통신 방향별로 서로 다른 암호키를 생성하는 함수이다.

</details>

- 공개키 연산은 **KEM**의 키 설정 구간에 한정한다.
- **DEM**은 **세션키**로 본문을 고속 암호화한다.
- **KDF**로 용도•방향별 키를 분리한다.

#### 한줄 요약

- 열쇠를 안전하게 합의해도 상대 신원을 확인하지 않으면 공격자가 양쪽과 각각 열쇠를 만들어 대화를 중간에서 읽을 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **키 스케줄**: 하나의 공유 비밀에서 연결 단계와 용도별 키를 순서대로 도출하고 갱신하는 절차이다.
- **연관 데이터 포함 인증 암호(Authenticated Encryption with Associated Data, AEAD)**: 본문의 기밀성과 본문•부가 데이터의 무결성을 함께 보호하는 암호 방식이다.

</details>

```text
하이브리드 암호 구조
├─ 인증 모듈
├─ 키 설정 모듈
├─ KDF•키 스케줄
└─ AEAD 모듈
```

가지의 의미: 인증•키 설정•키 분리•본문 보호 책임을 나눈 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 인증 모듈 | 공개키 소유자•협상 기록 검증 |
| 키 설정 모듈 | KEM 공유 비밀 생성 |
| KDF•키 스케줄 | **키 스케줄**로 단계•방향별 대칭키 분리 |
| AEAD 모듈 | **AEAD** 본문 암호화•태그 검증 수행 |


#### 한줄 요약

- 하나의 공유 비밀을 그대로 모든 곳에 쓰지 않고, KDF가 송신•수신과 연결 단계마다 다른 키를 만들어 한 키의 노출이 번지는 범위를 줄인다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **협상 기록 인증**: 양측이 교환한 알고리즘 제안과 선택 결과를 검증하여 다운그레이드 조작을 탐지하는 인증이다.
- **임시 타원곡선 디피-헬먼(Elliptic Curve Diffie-Hellman Ephemeral, ECDHE)**: 연결마다 임시 타원곡선 키를 만들어 공유 비밀을 합의하는 방식이다.
- **인증서•협상 기록 검증**: 상대 인증서와 알고리즘 협상 기록의 서명•무결성을 확인하는 단계이다.
- **ECDHE•KEM 키 설정**: 임시 키 합의 또는 KEM 캡슐화로 공유 비밀을 만드는 단계이다.
- **공유 비밀•방향별 키 도출**: 공유 비밀에서 송신•수신•용도별 키를 유도하는 단계이다.
- **AEAD 본문 보호**: 유도한 대칭키로 본문의 기밀성과 무결성을 보호하는 단계이다.

</details>

```text
알고리즘 제안•선택•인증서 수신
        │
        ▼
1. 인증서•협상 기록 검증
        ├─ 실패: 연결 중단
        └─ 성공
             │
             ▼
     2. ECDHE•KEM 키 설정
             │
             ▼
     3. 공유 비밀•방향별 키 도출
             │
             ▼
     4. AEAD 본문 보호
             │
             └── 보호된 레코드 전송
```

### 동작 원리

1. **인증서•협상 기록 검증**: **협상 기록 인증**으로 **인증서•협상 기록 검증**을 수행한다.
2. **ECDHE•KEM 키 설정**: **ECDHE** 또는 KEM으로 **ECDHE•KEM 키 설정**을 수행한다.
3. **공유 비밀•방향별 키 도출**: 같은 비밀에서 **공유 비밀•방향별 키 도출**을 수행한다.
4. **AEAD 본문 보호**: **AEAD 본문 보호**로 기밀성•무결성을 확보한다.


#### 한줄 요약

- 양측이 주고받은 알고리즘 목록까지 서명 검증에 포함해야 공격자가 중간에서 강한 방식을 지우고 약한 암호를 쓰게할 수 없다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **순방향 비밀성**: 장기 개인키가 유출되어도 이전 세션키와 암호문을 보호하는 성질이다.
- **RSA 키 전송**: 수신자의 RSA 공개키로 세션키를 암호화하여 전달하는 방식이다.
- **양자 내성 암호(Post-Quantum Cryptography, PQC)**: 양자컴퓨터 공격에도 안전하도록 설계한 암호 기술이다.
- **PQC KEM 결합**: 기존 키 합의와 양자 내성 KEM의 두 비밀을 KDF로 결합하는 방식이다.
- **ECDHE 기반**: 임시 타원곡선 키 합의로 공유 비밀을 설정하는 방식이다.

</details>

| 하이브리드 키 설정 | **ECDHE 기반** | **RSA 키 전송** | **PQC KEM 결합** |
|:---|:---|:---|:---|
| 적용 기준 | **순방향 비밀성**이 필요한 통신 | 기존 RSA 키 전송 호환 | **PQC** 전환기 통신 |
| 핵심 특징 | 임시 키 합의 후 AEAD | RSA 공개키 세션키 암호화 | 두 비밀의 KDF 결합 |
| 한계 | 인증 없으면 중간자 공격 | 개인키 유출 시 과거 복호화 | 실패 시 자동 약화 위험 |

> 요약: 인증•과거 보호•양자 대응으로 선택한다.

#### 한줄 요약

- 기존 키 합의와 새 KEM을 함께 쓸 때는 두 비밀을 정해진 KDF로 결합해야 하며, 새 방식 실패를 숨기고 기존 방식만 쓰면 양자 대응이 사라진다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **다운그레이드 공격**: 협상 정보를 조작하여 양측이 지원하는 방식보다 약한 알고리즘을 선택하게 하는 공격이다.
- **영역 분리**: 같은 공유 비밀에서 파생한 키가 용도와 방향에 따라 서로 대체되지 않도록 구분하는 원칙이다.
- **인터넷 표준 문서(Request for Comments, RFC) 9180**: HPKE의 KDF 영역 분리와 키 스케줄을 규정한 표준이다.
- **하이브리드 공개키 암호(Hybrid Public Key Encryption, HPKE)**: KEM•KDF•AEAD를 결합한 공개키 암호 체계이다.
- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 데이터 보호를 제공하는 프로토콜이다.
- **RFC 9846**: TLS 1.3의 하이브리드 키 교환 방식을 규정한 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 협상 조작 | **협상 기록 인증**으로 **다운그레이드 공격** 차단 | 약한 조합 선택 방지 |
| 키 설정과 본문 키 재사용 | **RFC 9180**의 KDF **영역 분리**와 **HPKE** 적용 | 키 용도 혼용 방지 |
| 구형 **TLS** 설계 잔존 | **RFC 9846** 기준 전환 | 순방향 비밀성 확보 |

#### 한줄 요약

- 상대와 협상 기록을 인증하고 공유 비밀에서 방향•용도별 키를 분리한 뒤 본문을 AEAD로 보호한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **하이브리드 키 설정 선택**: 순방향 비밀성과 양자 전환 요구에 따라 ECDHE 기반 또는 PQC KEM 결합을 결정하는 판단이다.

</details>

- 현재 통신은 **ECDHE 기반**, 양자 전환은 **PQC KEM 결합**을 택하는 **하이브리드 키 설정 선택**이 필요하다.

#### 한줄 요약

- 공개키와 대칭키를 함께 썼다는 사실만으로 충분하지 않으며, 상대 인증부터 키 결합과 데이터 보호까지 각 결과가 다음 단계의 신뢰 근거가 되어야 한다.
