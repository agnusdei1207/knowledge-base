## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **하이브리드 암호 (Hybrid Cryptography)**: 비대칭키(공개키)의 '안전한 배달' 장점과 대칭키의 '빛의 속도' 장점만 쏙쏙 뽑아 결합한 궁극의 실용 암호 체계다. 우리가 쓰는 웹(HTTPS/TLS)의 근간이다.
- **KEM (키 캡슐화 메커니즘)**: 통신 시작 전, 공개키를 써서 무작위로 만든 '일회용 대칭키(세션키)'를 안전하게 포장(캡슐화)해서 상대방에게 배달하는 과정이다.
- **DEM (데이터 캡슐화 메커니즘)**: KEM으로 합의한 일회용 대칭키를 가지고, 기가바이트 단위의 대용량 영상이나 파일을 급격히 빠른 속도로 암호화(AEAD)하는 과정이다.

</details>

- 정의: 무거운 공개키 연산은 **KEM 키 설정**에만 쓰고, 대용량 본문은 빠른 대칭키로 처리하는 **DEM 본문 보호** 활용 결합한 복합 암호 체계다.
- 배경: 비대칭키(공개키) 암호만으로는 용량이 큰 데이터(동영상 등)를 암호화할 때 서버 CPU가 뻗어버리는 **대용량 처리 한계** 명확히 존재했다.

#### 한줄 요약

- 열쇠 교환은 안전하지만 느린 공개키로, 실제 데이터 포장은 빠르고 가벼운 대칭키로 분업하는 찰떡궁합 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **세션키 (Session Key)**: 이번 한 번의 통신(세션) 동안만 쓰고, 브라우저 창을 닫거나 통신이 끝나면 즉각 쓰레기통에 버리는 일회용 대칭키다.
- **KDF (키 유도 함수)**: KEM으로 넘겨받은 원본 비밀 재료(마스터 키) 하나를 가지고, 송신용 키, 수신용 키, 무결성 검증용 키 등 여러 용도의 파생 키를 찍어내는 공장이다.

</details>

- **가성비 (비용 최적화)**: 연산이 무거운 공개키 암호화는 딱 한 번 '세션키 캡슐화(KEM)' 합의할 때만 최소한으로 써먹는다.
- **초고속 페이로드 (하이브리드 구조)**: 무거운 데이터 본문은 가볍고 빠른 **DEM (대칭키 AEAD)** 메커니즘을 통해 초고속으로 밀어낸다.
- **키 스케줄링**: 원본 공유 비밀에서 **KDF (키 유도 함수)** 를 돌려, 송수신 방향과 용도별 대칭키를 독립 도출해 낸다.

#### 한줄 요약

- 공개키와 대칭키의 장점만 비빔밥처럼 섞어서, 중간자 공격은 PKI 인증서로 막고 속도는 AEAD로 끌어올린 실전용 암호다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AEAD 모듈**: 본문을 암호화할 때, "이 데이터 변조 안 됐음!"을 증명하는 무결성 도장(태그)까지 한 번에 찍어주는 만능 대칭키 암호화 엔진이다.

</details>

```text
[ 하이브리드 암호 기반 키 설정 및 본문 보호 구조 ]

[ 1. 신원 인증 모듈 ] ── (수신자의 PKI 인증서를 까보고 찐인지 체크함)
      │
      ▼ (인증 성공)
[ 2. KEM 키 설정 모듈 ] ── (공개키로 세션키 재료(공유 비밀)를 캡슐화해서 던짐)
      │
      ▼ (캡슐 복구 완료)
[ 3. KDF / 키 스케줄 ] ── (공유 비밀을 믹서기에 돌려 송신용/수신용 대칭키를 분리 배급함)
      │
      ▼ (키 장전)
[ 4. DEM (AEAD) 모듈 ] ── (발급받은 대칭키로 대용량 본문을 초고속 암호화하고 태그 찍음)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **신원 인증 모듈** | "너 진짜 은행 맞아?" 하고 **상대방의 PKI 인증서와 서명을 철저한 검증함** | Auth Module |
| **KEM 키 설정 모듈** | 안전한 통신을 위해 **일회용 세션키(공유 비밀)를 공개키로 캡슐화해 쏴주는 놈** | KEM Module |
| **KDF (키 유도 함수)** | 공유 비밀 하나를 쪼개서 **송신용/수신용 등 여러 개의 파생 키를 낳는 공장** | KDF |
| **DEM (AEAD 모듈)** | KDF가 준 대칭키로 **기가바이트급 본문을 빛의 속도로 잠그고 무결성 태그 굽는 엔진** | DEM Module |

#### 한줄 요약

- 인증서로 신분 체크 $\to$ 세션키 캡슐 배달 $\to$ KDF로 키 증식 $\to$ AEAD로 고속 포장하는 무결점 사이클이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **협상 기록 (Transcript)**: 통신 초기(핸드셰이크)에 "우리 앞으로 통신할 때 AES-256 쓸까?" 하고 양쪽이 서로 떠든 대화 내용(파라미터)이다.
- **협상 기록 인증**: 해커가 중간에서 "얘네 똥컴이니까 구식 암호 쓰자"라고 몰래 대화를 조작(다운그레이드)하지 못하도록, 떠든 대화 내용 전체에 전자서명(도장)을 찍고 시작하는 거다.

</details>

```text
[ TLS 1.3 기반 하이브리드 암호 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [알고리즘 협상 및 인증서/협상 기록 철저한 검증]
│ (서로 인증서 교환하고, "우리 암호 방식 조작 안 당했지?" 체크함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [ECDHE / KEM 키 캡슐화 및 공유 비밀 설정]
│ (공개키로 캡슐 포장해서 세션키 재료(마스터 키)를 안전하게 교환함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [KDF 기반 방향별 세션키 도출 (영역 분리)]
│ (마스터 키를 갈아서 송신용 대칭키와 수신용 대칭키를 분리함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [DEM (AEAD) 본문 암호화 및 초고속 전송]
│ (분리된 대칭키로 대용량 본문을 초고속 잠그고, 무결성 태그 찍어 쏨)
└──────────────────────────────┘
```

### 동작 원리

1. 인증서/협상 기록 검증: 가짜 공개키 및 암호 레벨 낮추기(다운그레이드) 꼼수를 사전 차단함.
2. ECDHE/KEM 키 설정: 임시 키 합의(ECDHE)나 캡슐화(KEM)를 통해 마스터 공유 비밀을 창출함.
3. KDF 키 도출: KDF를 돌려 송신키, 수신키, 인증키 등 용도별 대칭키를 혼용 없이 뽑아냄.
4. AEAD 본문 보호: 생성된 대칭키로 페이로드(본문)의 기밀성과 조작 방지(무결성)를 동시 보장함.

#### 한줄 요약

- 통신 전 대화 기록까지 검증해서 조작을 막고, 방향별로 키를 쪼갠 뒤에 초고속 암호화에 돌입한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RSA 키 전송 (Legacy)**: 송신자가 세션키 만들어서 수신자 공개키로 무식하게 암호화해 던지는 옛날 방식.
- **ECDHE (순방향 비밀성)**: 세션마다 1회용 타원곡선 키를 새로 만들어서 교환하는 방식. 미래에 서버가 털려도 과거 데이터는 지킬 수 있는 PFS 끝판왕이다.
- **PQC KEM 결합**: 고전 수학(ECDHE)과 미래 양자 내성 수학(PQC) 알고리즘 두 개를 하이브리드로 동시에 적용하는 미래 대비 표준이다.

</details>

| 하이브리드 키 설정 | **RSA 키 전송 (구형)** | **ECDHE 기반 (현재 표준)** | **PQC KEM 결합 (미래 표준)** |
|:---|:---|:---|:---|
| 핵심 특징 | **옛날 옛적 쓰던 낡고 위험한 열쇠 배달** | **한 번 쓰고 미련 없이 버리는 일회용 도어락** | **외계인(양자컴퓨터) 쳐들어와도 끄떡없는 방공호** |
| 적용/동작 원리 | 송신자가 세션키 만들고 상대방 RSA 공개키로 암호화해서 던짐 | 매번 1회용 타원곡선 키를 합의한 후 AEAD 본문 암호화를 돌림 | 고전 수학(ECDHE)과 양자 내성 KEM 알고리즘 두 개를 동시 적용 |
| 최고 장점 | 구닥다리 시스템과 무조건 **호환됨(오래전부터 써옴)** | 내일 장기 키가 털려도 옛날 데이터는 안전한 **'순방향 비밀성(PFS)' 개꿀임** | 가까운 미래에 양자컴퓨터가 나와도 **암호문이 절대 안 풀림** |
| 치명적 한계 | 나중에 RSA 개인키 침해당하면 **과거 통신 데이터까지 줄초상(SNDL) 남** | 신원 인증(PKI) 절차 빼먹고 키부터 교환하면 **중간자(MITM)한테 전체 유출** | 두 알고리즘을 섞어 쓰다 보니 **계산량과 키 사이즈가 무지막지하게 커짐** |

#### 한줄 요약

- RSA 키 전송은 과거의 유물이며, 현재는 PFS를 보장하는 ECDHE, 양자 위협 시대엔 PQC KEM 결합이 국룰이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **다운그레이드 공격 (Downgrade Attack)**: 해커가 중간에서 "어이구, 얘네 구형 암호(DES/RC4 등)밖에 못 쓰네"라고 속여서 보안 수준을 강제로 낮춰버린 다음, 손쉽게 털어먹는 비열한 수법이다.
- **영역 분리 (Domain Separation)**: KDF로 키를 도출할 때, "이건 송신용! 이건 수신용!" 꼬리표(컨텍스트)를 달아서 절대로 키를 혼용하지 못하게 막는 철칙이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 해커가 중간에서 **구형 취약 암호로 다운그레이드시킴** | 암호 알고리즘 협상 과정(Plaintext)을 해커가 몰래 변조해 약한 암호를 쓰게 유도함 | 교환한 전체 대화 내용(파라미터)에 **'협상 기록 인증'을 강제함** | 약한 암호 조합으로 강제 유도하는 다운그레이드 및 MITM 원천 차단 |
| 하나의 세션키를 **송수신 양방향에 무지성으로 재사용함** | KDF(키 유도) 단계에서 용도별 꼬리표(컨텍스트)를 논리적으로 분리하지 않음 | **RFC 9180 (HPKE) 기반 철저한 키 '영역 분리(Domain Separation)' 적용** | 키 재사용으로 인한 암호학적 충돌 및 데이터 평문 노출 방어 |
| 구형 TLS 1.2 서버가 **장기 개인키 침해당하면서 옛날 데이터 다 뚫림** | RSA 키 전송 같은 구시대적 정적 키 교환 방식을 서버에 그대로 방치함 | RSA 키 전송을 영구 폐기하고 **'순방향 비밀성(PFS)'을 보장하는 TLS 1.3 강제 전환** | 미래의 수집 후 해독(SNDL) 위협으로부터 철통 방어 구축 |

#### 한줄 요약

- 통신 전 대화 조작 못하게 서명 찍고, 송/수신 키 겹치지 않게 분리하며, RSA 키 전송은 멸종시켜야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 비대칭키의 배포 안전성과 대칭키의 처리 속도를 결합하기 위해, **PKI 인증** 기반으로 **KEM** 키 설정을 수행하고 **AEAD(DEM)** 로 대용량 본문을 초고속 보호하며, 미래 위협을 막기 위해 낡은 RSA 전송을 버리고 **순방향 비밀성(ECDHE)** 기조를 확립함

#### 한줄 요약

- 하이브리드 암호는 느린 자물쇠(공개키)로 초고속 열쇠(세션키)만 안전하게 넘겨주고, 본 게임은 초고속 열쇠로 승부 보는 궁극의 아키텍처다.
