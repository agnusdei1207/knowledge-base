## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디지털 저작권 관리(Digital Rights Management, DRM)**: 파일 자체를 암호화해 사용 권한을 지속 통제하는 기술이다.
- **데이터 유출 방지(Data Loss Prevention, DLP)**: 정보 이동 경로에서 민감정보를 탐지•차단하는 통제이다.
- **정보유출 통제**: 기밀 문서나 개인정보가 인가되지 않은 외부로 나가는 것을 막는 체계이다.

</details>

- 정의/개념: 파일 암호화 중심의 **DRM** 및 전송 경로 검사 중심의 **DLP** 활용한 **정보유출 통제**이다.
- 배경/필요성: 문서 자체의 통제나 이동 경로의 차단 하나만으로는 다양한 유출 방식을 막을 수 없다.

#### 한줄 요약

- DRM은 문서를 암호화해 자물쇠를 채우고, DLP는 나가는 통로에서 민감 내용을 검사한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **암호화 기반 종단 통제**: 파일이 어디로 가든 암호화가 유지되어 권한 있는 사람만 읽을 수 있는 성질이다.
- **내용 기반 유출 탐지**: 키워드•패턴•지문으로 파일 안의 민감정보를 찾아내는 기술이다.

</details>

- DRM은 **암호화 기반 종단 통제** 활용 제공한다.
- DLP는 **내용 기반 유출 탐지** 기반 경로를 차단한다.
- 두 기술로 엔드포인트와 네트워크를 함께 통제한다.

#### 한줄 요약

- 문서 밖 유출은 암호화로 막고 통로 유출은 내용 검사로 막아 상호 보완한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **키 관리 서버(Key Management Server, KMS)**: DRM 암호키와 사용자 권한을 관리하는 서버이다.
- **DLP 에이전트•게이트웨이**: 단말 매체 제어와 네트워크 트래픽 검사를 수행하는 구성요소이다.

</details>

```text
정보유출 통제 구조
├─ 데이터 탐지•식별
├─ DRM 파일 암호화
├─ DRM 키•권한 통제
├─ DLP 경로•내용 검사
└─ 유출 탐지•감사
```

| 구성요소 | 책임 |
|:---|:---|
| 데이터 탐지•식별 | 보호할 민감정보와 파일 분류 |
| DRM 파일 암호화 | 생성 시 문서 암호화 |
| DRM 키•권한 통제 | **KMS** 기반 복호화•열람 권한 관리 |
| DLP 경로•내용 검사 | **DLP 에이전트•게이트웨이** 기반 유출 차단 |
| 유출 탐지•감사 | 차단 로그와 이상 행위 기록 |

#### 한줄 요약

- DRM은 파일을 암호화해 키 서버로 권한을 제어하고 DLP는 통로에서 내용을 검사해 차단한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **문서 암호화•권한 확인**: DRM이 파일을 암호화하거나 열람 요청 시 키 서버에서 권한을 검증하는 단계이다.
- **정책•패턴•지문 검사**: DLP가 전송되는 파일의 내용을 검사해 민감정보 유무를 확인하는 단계이다.

</details>

```text
1. [DRM 흐름]
   문서 생성•저장 ──► 문서 암호화 ──► 외부 유출 ──► (권한 없음) 열람 실패

2. [DLP 흐름]
   파일 외부 전송 요청 ──► 정책·패턴·지문 검사 ──► (민감정보 탐지) 전송 차단
```

### 동작 원리

1. 문서 생성·저장: DRM 파일 암호화
2. 외부 유출: 권한 없으면 DRM 열람 실패
3. 파일 전송 요청: DLP 전송 경로 검사
4. 민감정보 탐지: 정책 위반 시 DLP 전송 차단

#### 한줄 요약

- DRM은 유출되어도 못 읽게 하고 DLP는 나가는 것 자체를 막는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **문서 종속**: 보호 대상이 문서 파일 자체에 한정되는 특성이다.
- **경로 종속**: 보호 대상이 네트워크나 매체의 전송 행위에 한정되는 특성이다.

</details>

| 통제 방식 | DRM | DLP |
|:---|:---|:---|
| 적용 기준 | 생성 시 원천 보호 | 전송•유출 경로 통제 |
| 핵심 특징 | 파일 암호화•권한 제어 | 식별•패턴•지문 검사 차단 |
| 한계 | **문서 종속**•호환성 제한 | **경로 종속**•암호화 파일 검사 불가 |

> 요약: 파일 자체를 보호할지, 나가는 통로를 보호할지 선택하는 것이 핵심이다.

#### 한줄 요약

- DRM은 파일 호환성 문제가 있고 DLP는 이미 암호화된 파일은 내용을 검사하기 어렵다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **복호화 예외**: 외부 기관 제출을 위해 특정 파일의 DRM 암호를 푸는 예외 승인 절차이다.
- **암호화 통신(TLS) 검사**: HTTPS 등으로 암호화된 트래픽을 프록시에서 복호화해 DLP로 검사하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 외부 기관과 협업 시 DRM 파일 열람 불가 | **복호화 예외** 결재 연동 | 안전한 파일 반출 |
| DLP가 DRM 문서를 암호화 파일로 인식해 검사 불가 | DRM과 DLP 연동 | 복호화 후 내용 검사 |
| 웹메일 등 암호화 통신을 쓰면 DLP 탐지 우회 | **암호화 통신(TLS) 검사** 적용 | 암호화 경로 가시성 |

#### 한줄 요약

- DRM 해제 시 승인 절차를 거치고 DLP가 암호화된 트래픽과 DRM 문서를 검사할 수 있게 연동한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **상호 보완 아키텍처**: 파일 보안과 경로 차단을 결합해 단일 통제의 한계를 넘는 구조이다.

</details>

- DRM과 DLP의 한계를 덮는 **상호 보완 아키텍처** 기반 내부자 정보유출을 막는다.

#### 한줄 요약

- 파일 자물쇠(DRM)와 통로 검사소(DLP)를 함께 운영해야 다양한 유출 시도를 막을 수 있다.
