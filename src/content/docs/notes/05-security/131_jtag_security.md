## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **JTAG(Joint Test Action Group)**: 칩 시험•경계주사•디버그용 하드웨어 접근 방식이다.
- **JTAG 보안**: 장치 수명주기와 권한에 따라 TAP 접근을 제한하는 하드웨어 통제이다.

</details>

- 정의/개념: **JTAG 보안**은 수명주기와 권한에 따라 TAP 접근을 제한하는 통제이다.
- 배경/필요성: 출고 뒤 열린 디버그 포트에서는 펌웨어•키가 추출될 가능성이 있다.

#### 한줄 요약

- 승인된 수리자에게 **한시 JTAG 권한**만 부여

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **수명주기 상태**: 제조•운영•수리 단계별 JTAG 기능과 전이 조건을 구분한 장치 상태이다.
- **디버그 인증**: 장치•작업자•명령 범위를 검증한 뒤 잠금을 제한적으로 해제하는 통제이다.

</details>

- 제조•운영•수리별 **수명주기 상태**가 핵심이다.
- **디버그 인증**으로 잠금을 제한적으로 해제한다.
- 자원•명령•시간 범위에 필요한 최소 권한만 부여한다.

#### 한줄 요약

- 포트를 영구 폐쇄하면 수리가 어렵고 계속 열면 장악되므로 제품 상태에 따라 권한을 달리하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **TAP(Test Access Port)**: JTAG 명령•데이터를 전달하는 인터페이스이다.
- **경계주사**: 보드 핀 상태를 관측•제어하는 시험 기법이다.
- **IEEE(Institute of Electrical and Electronics Engineers)**: 전기전자 기술표준을 개발하는 학회이다.
- **IEEE 1149.1**: TAP와 경계주사의 구조•명령 표준이다.
- **CPU(Central Processing Unit) 접근**: 처리기와 메모리를 읽고 쓰는 디버그 권한이다.

</details>

```text
JTAG 접근 통제
├─ IEEE 1149.1 TAP•핀
├─ 장치 수명주기 정책
├─ 작업자•장치 인증기
├─ 명령•자원 권한 게이트
└─ 감사로그•재잠금•폐기
```

| 구성요소 | 책임 |
|:---|:---|
| IEEE 1149.1 TAP•핀 | **TAP**와 **경계주사** 명령 전달 |
| 장치 수명주기 정책 | 단계별 기능•전이 조건 정의 |
| 작업자•장치 인증기 | 인증서•토큰•용도 검증 |
| 명령•자원 권한 게이트 | **CPU 접근** 제한 |
| 감사로그•재잠금•폐기 | 작업 기록•단기 권한 회수 |

- **IEEE**의 **IEEE 1149.1**을 기준으로 시험 접근 구조를 식별한다.

#### 한줄 요약

- 수명 정책과 인증기가 작업자를 확인하면 권한 게이트가 승인된 기능만 열어 줌이 핵심이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RMA(Return Merchandise Authorization)**: 회수 제품에 진단•수리 접근을 승인하는 절차이다.
- **JTAG 접근 통제**: 상태•작업자•명령•만료시간을 검증하는 통제이다.
- **수명 상태•작업자 자격 검증**: 장치 상태•인증서•수리 승인을 확인하는 단계이다.
- **허용 명령•자원•만료 시각 설정**: 작업에 필요한 접근 범위와 종료 시각을 정하는 단계이다.
- **실행 명령•결과•작업자 기록**: 디버그 행위와 결과 및 수행 주체를 보존하는 단계이다.
- **세션 폐기•재잠금**: 작업 종료 후 토큰•임시 키를 없애고 포트를 잠그는 단계이다.

</details>

```text
장치•작업•시간 요청
   │
   ▼
1. 수명 상태·작업자 자격 검증
   ├─ 부적합 ──► 접근 거부
   └─ 적합
        │
        ▼
2. 허용 명령·자원·만료 시각 설정
   │
   ▼
3. 실행 명령·결과·작업자 기록
   │ 작업 종료•만료
   ▼
4. 세션 폐기·재잠금
   │
   ▼
작업 종료 상태
```

### 동작 원리

1. 수명 상태·작업자 자격 검증: 인증서·RMA 상태 판정
2. 허용 명령·자원·만료 시각 설정: 접근 범위 제한
3. 실행 명령·결과·작업자 기록: 감사 증적 보존
4. 세션 폐기·재잠금: 토큰·임시 키 제거

#### 한줄 요약

- 수리 목적과 권한을 검증하고 필요한 명령만 허용한 뒤 세션과 임시 비밀을 폐기하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **디버그 잠금**: 운영 단계에서 CPU•메모리 접근 등 위험한 디버그 명령을 비활성화하는 통제이다.
- **디버그 처리기 접근**: JTAG의 CPU•메모리 접근 범위를 제한하는 기준이다.

</details>

| JTAG 운영 방식 | 개방형 디버그 | 영구 비활성화 | 인증형 디버그 |
|:---|:---|:---|:---|
| 적용 기준 | 격리된 개발•시험 장치 | 현장 수리 불필요 | 제조•수리 기능 유지 |
| 핵심 특징 | 인증 없이 기능 허용 | **디버그 잠금**으로 완전 차단 | **디버그 인증** 후 범위•시간 제한 |
| 한계 | 펌웨어•키 추출 | 장애 분석•복구 불가 | 인증키•해제 구현 공격면 |

- 인증형 방식은 **디버그 처리기 접근** 범위를 작업 목적에 맞게 제한한다.

> 요약: 수리 필요성과 공격면에 따라 잠금 방식을 선택하는 것이 핵심이다.

#### 한줄 요약

- 운영 장치는 인증형 디버그로 필요한 명령만 정해진 시간 동안 여는 방식이 적합하다는 점이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IEEE 1687**: 칩 내부 계측기 접근 구조를 다루는 표준이다.
- **P1687 개정안**: IEEE 1687의 개정 과정에 있는 표준안으로 내부 디버그 경로의 최신 요구사항을 확인하는 기준이다.
- **RMA JTAG 수리**: 반품 장치의 권한을 신원•명령•시간으로 제한하는 절차이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| TAP 구조가 제각각이면 시험 경계가 불명확함 | **IEEE 1149.1** 준수 | TAP•명령 구조 명확화 |
| 숨은 계측 경로가 남으면 잠금을 우회할 수 있음 | **IEEE 1687**과 **P1687 개정안** 확인 | 내부 디버그 경로 관리 |
| RMA 권한이 장기 유지되면 현장 악용이 가능함 | **RMA JTAG 수리**에 단기 토큰 적용 | 신원•범위•시간 제한 |

#### 한줄 요약

- RMA 장치는 작업자 인증서와 허용 명령을 검증한 경우만 JTAG를 열고 종료 즉시 토큰을 폐기해 재잠근다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **한시 권한**: 승인된 수리 작업의 명령•자원•시간만 허용하고 종료 즉시 회수하는 원칙이다.
- **인증형 디버그**: 승인된 작업자에게 제한된 JTAG 권한만 부여하는 방식이다.

</details>

- **한시 권한** 원칙으로 수리 시 **인증형 디버그**만 허용한다.

#### 한줄 요약

- 승인 작업만 허용하고 종료 즉시 **JTAG 재잠금**
