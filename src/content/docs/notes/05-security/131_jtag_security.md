## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **JTAG 디버그 포트 보안(JTAG Security / IEEE 1149.1 TAP & IEEE 1687)**: 반도체 칩 제조 시 기판 결함 검사(Boundary Scan) 및 펌웨어 개발·디버깅을 위해 탑재된 하드웨어 테스트 접근 포트(TAP: Test Access Port)를 통한 비인가 접근을 차단하고, 장치 수명주기(Lifecycle) 및 작업자 인증 권한에 따라 디버그 인터페이스의 활성화 여부와 CPU/메모리 접근 범위를 엄격히 제어하는 하드웨어 보안 기술.
- **상용 출하 후 물리적 디버그 포트 방치 결함(Exposed Debug Port Defect)**: 개발 및 공정 검사용으로 사용되던 JTAG/SWD 핀이 양산 제품 출하 후에도 개방된 상태로 방치될 경우, 공격자가 물리적 프로브나 디버거(J-Link 등)를 연결하여 CPU 실행을 정지(Halt)시키고 플래시 메모리 덤프 및 암호키를 평문으로 직접 추출하는 치명적 구조적 결함.

</details>

- 정의/개념: 기기의 물리적 제어권을 방어하기 위해 **기기 수명주기 상태(Lifecycle State) 관리 $\rightarrow$ 공장 출하 시 JTAG 퓨즈 단선(eFuse Blowing) 또는 잠금 $\rightarrow$ A/S 반품(RMA) 시 암호학적 챌린지-응답 디버그 인증 $\rightarrow$ 최소 권한 메모리 접근 통제 $\rightarrow$ 작업 완료 후 세션 자동 재잠금(Relocking)** 을 집행하는 **하드웨어 디버그 인터페이스 보안 아키텍처**
- 배경/필요성: 스마트 기기, 자동차 전장 ECU, 국방 무기체계의 하드웨어 칩셋에 대한 로컬 물리적 공격(Physical Extraction) 위협을 차단하면서도, 제품 고장 시 정밀 사후 분석(RMA)을 지원할 수 있는 가역적 통제 기제 요구

#### 한줄 요약
- JTAG 보안은 장치 수명주기와 암호학적 인증을 기반으로 TAP 디버그 포트 접근을 통제한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **JTAG 보안 3대 핵심 통제 메커니즘**:
  - **수명주기 상태 연동 (Lifecycle State Binding)**: 개발(Open) $\rightarrow$ 제조(Test) $\rightarrow$ 양산 운영(Locked) $\rightarrow$ 수리(RMA Authenticated) $\rightarrow$ 폐기(Destroyed) 상태별 하드웨어 접근 수준 차등화.
  - **암호학적 디버그 인증 (Challenge-Response Authentication)**: 사전 공유키(PSK) 또는 공개키(ECC) 기반으로 인증 토큰을 검증한 후에만 한시적으로 TAP 활성화.
  - **세분화된 접근 권한 제어 (Granular Debug Authorization)**: CPU 전체 레지스터/RAM 덤프를 차단하고 로그 읽기 또는 칩셋 리셋 명령만 선별 허용.

</details>

- **하드웨어 레벨의 강제 잠금(Hardware Enforced Lock)**: 소프트웨어 설정이 아닌 물리적 eFuse 레지스터 또는 하드웨어 보안 모듈(HSM)에 의해 디버그 버스 신호 제어
- **단기 임시 세션 부여(Time-bound Access)**: 디버그 인증 통과 시에도 무제한 권한을 주지 않고 수리 세션 만료 타이머 종료 시 자동으로 포트를 영구/임시 재잠금
- **IEEE 1149.1 및 IEEE 1687 표준 정합성**: 외부 표준 TAP 인터페이스뿐만 아니라 칩 내부의 온칩 인스트루먼트(Internal JTAG) 네트워크까지 포괄적 보안 통제

#### 한줄 요약
- 수명주기 상태 기반 제어, 암호학적 챌린지-응답 인증, 세분화된 최소 권한, 자동 재잠금을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **JTAG 보안 4대 핵심 아키텍처 컴포넌트**:
  1. **IEEE 1149.1 TAP Controller**: TCK(클록), TMS(모드), TDI(입력), TDO(출력), TRST(리셋) 5개 핀 인터페이스.
  2. **Lifecycle Controller (eFuse Matrix)**: 장치의 수명주기 상태를 영구 기록하는 OTP 퓨즈 매트릭스.
  3. **Debug Authentication Module (DAM)**: 암호 가속기 기반 챌린지 생성 및 서명 토큰 검증기.
  4. **Access Control Logic (Gatekeeper)**: 인증 결과에 따라 Boundary Scan, Memory Scan, CPU Core 접근을 필터링하는 하드웨어 게이트.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 물리 디버그 인터페이스 계층 (IEEE 1149.1 TAP Physical Layer) ]     │
│  └─ [ TCK / TMS / TDI / TDO / TRST 핀 연결 ➔ 외부 디버거 케이블 접촉 ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (디버그 접근 요청)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 하드웨어 수명주기 판별 계층 (Lifecycle Controller & eFuse) ]        │
│  ├─ [ 개발(Dev) 단계 ] ➔ 100% 디버그 포트 전면 개방                    │
│  ├─ [ 양산(Customer) 단계 ] ➔ eFuse 락킹으로 JTAG 버스 신호 기계적 차단 │
│  └─ [ 반품(RMA) 단계 ] ➔ 암호학적 디버그 인증 모듈(DAM)로 트랩 분기     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (RMA 상태 진입 시)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 암호학적 디버그 인증 계층 (Debug Authentication Module: DAM) ]     │
│  ├─ 1. 칩 내부 TRNG 난수 ➔ 외부 엔지니어에게 챌린지(Challenge) 송신     │
│  ├─ 2. 엔지니어 서명 토큰 수신 ➔ 제조사 루트 공개키로 ECDSA 서명 검증  │
│  └─ [ 3. 인증 성공 시 ➔ 1시간 한시적 임시 세션 키 및 디버그 토큰 발급 ]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (세분화된 접근 권한 인가)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 하드웨어 접근 통제 게이트 계층 (Debug Access Gatekeeper) ]          │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ Boundary Scan 레벨 (허용) ]     │ [ CPU Core & RAM 덤프 (차단) ]      │
│ ├─ 기판 핀 단선/단락 검사 허용     │ ├─ 마스터 암호키 메모리 영역 차단   │
│ └─ 칩셋 리셋 및 진단 로그 추출    │ └─ [ 타이머 만료 시 즉시 자동 재잠금]│
└───────────────────────────────────┴─────────────────────────────────────┘
```

선의 의미: TAP 핀 접근 시 수명주기 상태를 확인하고, RMA 단계에서는 암호학적 인증(DAM)을 거쳐 최소 권한 게이트를 선별 개방하는 구조

| 컴포넌트 | 핵심 역할 및 기능 | 구현 기술 및 규격 | 비고 |
|:---|:---|:---|:---|
| **TAP 컨트롤러** | IEEE 1149.1 표준 16상태 FSM 기반 디버그 명령어 파싱 및 실행 | TCK, TMS, TDI, TDO, TRST | Interface |
| **수명주기 제어기** | OTP(One-Time Programmable) eFuse 기반 기기 수명주기 상태 천이 관리 | eFuse Array, HW State Machine | State Engine |
| **디버그 인증 모듈** | 챌린지-응답 기반 암호 인증 및 디지털 서명 토큰 유효성 검증 | ECDSA-P256, SHA-256, TRNG | Authentication|
| **접근 통제 게이트** | 인증된 보안 레벨에 따라 CPU 코어, 시스템 버스, 메모리 영역 접근 필터링 | AHB/AXI Debug APB Bridge, MPU | Access Gate |
| **세션 타이머/재잠금**| 정해진 시간 경과 또는 리셋 시 디버그 포트를 초기 잠금 상태로 자동 복원 | Monotonic Watchdog Timer | Relocking |

#### 한줄 요약
- TAP 컨트롤러, eFuse 수명주기 제어기, DAM 인증 모듈, 접근 통제 게이트, 세션 재잠금 엔진으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **JTAG RMA 안전 디버깅 5단계 프로세스**:
  1. 엔지니어가 JTAG 디버거를 연결하고 디버그 세션 개시 요청
  2. 기기 수명주기 상태(RMA) 확인 및 칩 내부 난수 챌린지 생성
  3. 본사 인증 서버에서 서명된 디버그 토큰을 기기로 전송
  4. 칩 내부 공개키로 서명 검증 및 한시적 최소 디버그 권한 인가
  5. 진단 수행 후 세션 만료 또는 케이블 분리 시 자동 재잠금

</details>

```text
1. [디버그 연결] A/S 센터 엔지니어가 반품된 IoT 보드에 JTAG 디버거 연결
            │
            ▼
2. [상태 확인 및 챌린지 발급]
    ├─ 칩 수명주기 확인 ➔ 양산 잠금(Field Lock) 상태에서 RMA 모드 요청 인지
    └─ [칩 내부 TRNG 난수 발생 ➔ 256비트 챌린지($C$)를 엔지니어 PC로 반환]
            │
            ▼
3. [본사 토큰 서명 및 주입]
    ├─ 엔지니어 PC ➔ 본사 인증 서버에 챌린지($C$) + 엔지니어 ID 전송
    └─ [본사 개인키로 서명된 인증 토큰($\text{Token} = \text{Sign}_{SK}(C \parallel \text{Perm})$)을 칩으로 전송]
            │
            ▼
4. [칩 내부 서명 검증 및 한시 개방]
    ├─ DAM 모듈이 Secure ROM 내 공개키($PK$)로 토큰 서명 100% 검증
    ├─ 검증 성공 시 지정된 핀셋 권한(예: Error Log Read Only)만 활성화
    └─ [하드웨어 워치독 타이머(1시간) 가동 시작]
            │
            ▼
5. [진단 완료 및 자동 재잠금]
    ├─ 고장 진단 로그 덤프 완료 후 수리 작업 종료
    └─ [타이머 만료 또는 전원 리셋 발생 ➔ 디버그 포트 즉각 자동 재잠금(Locked)]
```

**동작 원리**

1. **상태 기반 물리적 차폐**: 양산 출하 시 일반 사용 환경에서는 JTAG 버스 신호선이 기계적으로 차단되어 해킹 불가
2. **재전송 공격(Replay Attack) 방어**: 매 접속 시도마다 새로운 난수 챌린지를 생성하여 과거 캡처된 서명 토큰 재사용 차단
3. **권한의 세분화(Permission Scoping)**: 인증 토큰 내에 허용된 작업 범위(JTAG 명령어 화이트리스트)를 명시하여 메모리 덤프 방지
4. **시한부 접근성(Time-limited Access)**: 하드웨어 타이머를 통해 수리 세션 종료 후 포트가 무기한 열려 있는 보안 공백 제거
5. **감사 추적성(Auditability)**: 본사 인증 서버에 어떤 엔지니어가 언제 어떤 칩셋의 디버그를 승인받았는지 불변 감사 로그 기록

#### 한줄 요약
- 디버그 연결, 챌린지 발급, 본사 서명 토큰 주입, 칩 내부 서명 검증/개방, 타이머 만료 시 자동 재잠금 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **JTAG 포트 3대 잠금/보안 방식 비교**:
  - 영구 퓨즈 단선 (Permanent Fuse Blowing): 출하 시 eFuse를 완전히 끊어 영구 비활성화 (가장 안전하나 A/S 불가).
  - 비밀번호 기반 잠금 (Password-based Lock): 고정된 패스워드 입력 시 개방 (패스워드 하드코딩 및 유출 취약).
  - 암호학적 인증 디버그 (Cryptographic Authenticated Debug): 챌린지-응답 기반 공개키 인증 (표준 권장).

</details>

| 비교 항목 | 영구 퓨즈 단선 (Fuse Blowing) | 고정 비밀번호 잠금 (Password Lock) | 암호학적 인증 디버그 (Authenticated) |
|:---|:---|:---|:---|
| **잠금 메커니즘** | **물리적 eFuse 영구 절단 (단방향)** | **칩 내 고정 패스워드 레지스터 비교** | **비대칭키 기반 챌린지-응답 전자서명** |
| **사후 A/S 수리** | **불가능 (칩 폐기 또는 교체 필요)**| 가능 (패스워드 입력 시 해제) | **가능 (공인된 엔지니어 한정 승인)** |
| **보안 강도** | **최상 (물리적 차단으로 침해 0%)** | 낮음 (무차별 대입, 역공학 유출) | **최상 (재전송 공격 및 도청 방어)** |
| **권한 통제** | 전체 영구 비활성화 (0 or 1) | 전체 개방 (All or Nothing) | **명령어 및 메모리 영역별 세분화** |
| **적용 권장 분야** | 일회용 군사 센서, 스마트카드 | 저가형 완구, 비민감 IoT | **자율주행차 ECU, 스마트폰, 고가 IoT** |

#### 한줄 요약
- 퓨즈 단선은 A/S 포기형 영구 차단, 비밀번호는 유출 취약, 암호학적 인증은 안전한 사후 A/S와 보안의 최적 조합이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **IEEE 1149.1 (표준 JTAG) 및 IEEE 1687 (IJTAG / 온칩 계측 네트워크)**: 하드웨어 테스트 및 내부 계측 인터페이스 국제 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 양산 제품 출하 시 PCB 상에 JTAG 테스트 패드가 노출되어 **공격자가 프로브를 접촉하고 펌웨어 덤프 및 암호키를 직접 추출** | **IEEE 1149.1 준수, 제조 공정 완료 시 OTP eFuse를 양산 잠금(Field Lock) 모드로 전환하고 테스트 패드를 내층(Inner Layer)으로 배치** | 물리적 JTAG 핀 접촉을 통한 펌웨어 무단 탈취 100% 원천 차단 |
| 수리 엔지니어 편의를 위해 마스터 JTAG 비밀번호를 공용으로 설정하여 **비밀번호 유출 시 동일 제조사 전 제품의 하드웨어 보안 붕괴** | **고정 패스워드를 전면 폐기하고, 본사 PKI 인증 서버와 연동된 챌린지-응답 기반 비대칭키(ECDSA) 디버그 인증 파이프라인 구축** | 공용 키 유출 위험 0% 및 개별 기기별 디버그 격리 보증 |
| 외부 JTAG 포트는 잠갔으나 칩 내부의 온칩 인스트루먼트(IEEE 1687 IJTAG) 망이 개방되어 **우회 경로를 통해 내부 레지스터가 조작되는 취약점 발생** | **IEEE 1687 및 P1687.1 보안 표준 적용, 내부 계측 인스트루먼트 네트워크에 대해 하드웨어 게이트키퍼 보안 통제 일괄 적용** | 칩 내부 은닉 디버그 경로를 통한 백도어 우회 공격 100% 차단 |

#### 한줄 요약
- eFuse 양산 잠금으로 덤프를 막고, ECDSA 디버그 인증으로 공용 키 유출을 방어하며, IEEE 1687 통제로 백도어를 차단한다.

## Ⅶ. 결론

- 하드웨어 칩셋의 물리적 안전성과 사후 유지보수성(RMA)을 동시에 충족하는 최전선 방어 체계인 **JTAG 디버그 포트 보안 아키텍처**는 임베디드 및 엔드포인트 하드웨어 보안의 핵심 필수 요소이며, 실무 구현 시 **IEEE 1149.1 및 IEEE 1687 국제 표준 정합성 확보**, **eFuse 기반 하드웨어 수명주기(Lifecycle) 엄격 통제**, **챌린지-응답 기반의 강력한 암호학적 디버그 인증(DAM) 도입**, **최소 권한 접근 및 시한부 자동 재잠금(Relocking) 체계**를 통합 구축하여 최고 수준의 물리적 접근 제어와 제조·수리 신뢰성을 완성

#### 한줄 요약
- IEEE 1149.1/1687 표준과 eFuse 수명주기 통제 및 챌린지-응답 인증을 통해 완벽한 JTAG 디버그 보안을 완성한다.
