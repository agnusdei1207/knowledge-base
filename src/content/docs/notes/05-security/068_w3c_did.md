## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **W3C (월드 와이드 웹 컨소시엄)**: 웹 기술 및 분산 신원 생태계 글로벌 기술 표준을 제정하는 국제 규격 제정 기구
- **DID (분산 식별자)**: 중앙 등록기관 없이 자기주권형 암호키 쌍과 바인딩되어 고유 식별 및 독립 검증이 가능한 URI 표준 식별자
- **W3C DID 표준**: DID 식별자 구문 구조, DID 문서 스키마, 검증 관계 및 DID 해석기 동작 알고리즘을 규정한 표준 권고안
- **URI (통합 자원 식별자)**: `did:method:method-specific-id` 구조를 갖는 인터넷 자원 식별 표준 문자열 형식

</details>

- 정의: `did:method:id` 체계를 통해 중앙 기관 없이 암호학적 제어권을 증명하는 W3C 분산 식별자 데이터 모델 및 해석 표준 규격
- 배경: 벤더 및 플랫폼별 상이한 식별자 구현으로 인한 상호운용성 저하와 키 검증 호환성 결여 문제 해결 필요성

#### 한줄 요약

- 표준 URI 기반의 DID 문서 및 검증 관계를 정의하여 제어자 중심의 분산 신원 해석 체계 보장

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DID 문서 (DID Document)**: DID 주체의 공개키, 인증 메커니즘, 검증 관계, 서비스 엔드포인트를 담은 JSON-LD 데이터 구조
- **검증 관계 (Verification Relationship)**: 공개키가 서명 검증(assertionMethod), 신원 인증(authentication), 키 합의(keyAgreement) 중 어떤 용도로 사용 가능한지 명시하는 목적 제약 매핑
- **DID 방법 (DID Method)**: 특정 블록체인, DLT, 분산 저장소 상에서 DID 및 DID 문서를 CRUD 처리하는 구현 규격 명세

</details>

- **URI 구문 표준화**: `did:method:id` 형식을 준수하여 전역 유일성 및 방법별 독립적 해석 알고리즘 보장
- **검증 관계 목적 분리**: DID 문서 내 공개키 용도를 세분화하여 단일 키 침해 피해 방지 및 기능별 접근 제어 집행
- **저장소 거버넌스 분리**: 이기종 블록체인 및 분산 원장의 CRUD 동작을 DID 방법 레벨에서 독립 정의하여 상호운용성 확보

#### 한줄 요약

- `did:method:id` 구문과 DID 문서 내 검증 관계(Verification Relationship) 설계를 통한 용도별 공개키 통제 달성

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DID 주체 (DID Subject)**: 해당 DID 식별자가 나타내는 사람, 조직, 기기, 개체 또는 데이터 대상
- **제어자 (DID Controller)**: DID 문서의 갱신, 키 회전 및 비활성화 권한을 가짐을 암호학적으로 증명 가능한 주체
- **DID 해석기 (DID Resolver)**: DID URI를 파싱하고 대상 DID 방법에 맞춰 분산 저장소에서 최신 DID 문서를 해소(Resolution)하는 소프트웨어
- **해석 메타데이터 (Resolution Metadata)**: DID 문서 해소 결과, 조회 에러 코드, Content-Type 및 비활성화 상태 메타정보

</details>

```text
                     [DID 주체 / 제어자]
                              │
                            [DID]
                              │
                         [DID 방법]
                              │
                         [DID 해석기] ── [DID 문서 / 검증 관계]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **DID 주체 / 제어자** | 식별 대상 지정 및 비밀키 기반 DID 문서 생성/수정/폐기 통제권 행사 | Subject / Controller |
| **DID 식별자** | `did:method:id` 고유 문자열 구조로 식별 및 방법 지정 매핑 | URI Scheme |
| **DID 방법 (Method)** | 블록체인/저장소별 CRUD(생성·조회·갱신·비활성화) 인터페이스 명세 정의 | Implementation |
| **DID 해석기 (Resolver)** | DID 입력 수신 후 분산 저장소 조회 기반 최신 DID 문서 및 메타데이터 반환 | Resolution Engine |
| **DID 문서 / 검증 관계** | 공개키 목록, 엔드포인트 및 목적별(assertion, auth 등) 검증 관계 제공 | JSON-LD Document |

#### 한줄 요약

- DID 식별자 수신 시 해석기가 DID 방법 명세에 따라 저장소를 조회하여 최신 DID 문서와 검증 관계 도출

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **현재 DID 문서 (Active DID Document)**: 해소 시점에 분산 저장소에서 추출된 활성 상태의 최신 암호키 및 검증 관계 문서
- **키 용도 판정 (Key Purpose Verification)**: 서명에 사용된 공개키가 DID 문서 내 명시된 목적(assertionMethod 등)과 일치하는지 심사하는 과정

</details>

```text
[검증자]
      │
      └── 검증 대상 DID 해석 요청
                  │
                  ▼
[DID 해석기]
      │
      ▼
1. DID URI / 방법 구문 해석
      │
      └── 현재 상태 조회
                  │
                  ▼
[DID 방법]
      │
      ▼
2. 최신 DID 문서 / 상태 해석
      │
      └── DID 문서 / 상태 반환
                  │
                  ▼
[DID 해석기]
      │
      ▼
3. 문서 / 해석 메타데이터 검증
      │
      └── 문서 / 해석 메타데이터 전달
                  │
                  ▼
[검증자]
      │
      ▼
4. 키 용도 / 제어 상태 판정
      │
      ▼
[검증 결과 수용]
```

### 동작 원리

1. DID URI 파싱: 식별자 접두사, 방법명(Method), 고유 ID 구문 분리
2. 분산 저장소 조회: DID 방법 드라이버를 통해 블록체인 내 최신 DID 문서 및 비활성화 상태 추출
3. 메타데이터 검증: 반환된 문서의 JSON-LD 스키마 정합성 및 해석 에러 상태 확인
4. 검증 관계 판정: 전자서명에 사용된 공개키의 용도 부합성 및 제어권 유효성 최종 평가

#### 한줄 요약

- DID 구문 분석, 방법별 저장소 해소, 데이터 모델 정합성 검증 및 키 용도 평가를 통한 신뢰성 확인

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 식별자 (Centralized Identifier)**: 서비스 제공자가 자체 DB에 사용자 계정을 발급 및 단독 관리하는 방식
- **연합 식별자 (Federated Identifier)**: IdP(Google, Kakao 등)가 사용자 식별 토큰을 발행하고 중계하는 중앙집중형 연동 방식

</details>

| 식별자 관리 방식 | **W3C DID 표준** | **중앙 식별자 (DB)** | **연합 식별자 (OAuth/IdP)** |
|:---|:---|:---|:---|
| 관리 주체 | **사용자(제어자)**가 직접 암호키 생성 및 소유 | 서비스 제공 기업의 중앙 DB 종속 | 거대 IdP(빅테크) 기업 중심 통제 |
| 신뢰 검증 메커니즘 | **W3C DID 표준** 기반 비대칭 암호키 및 분산 원장 해소 | 단일 DB 내 ID/PW 및 세션 조회 | IdP 발급 인가 토큰(JWT) 검증 |
| 장단점 및 한계 | 완벽한 자기주권 보장 반면 **키 복구 및 방법별 파편화 관리 부담** | 구축 간편성 대비 **중앙 해킹 시 전면 유출 및 단일 장애점(SPOF)** | 연동 편의성 대비 **IdP 종속성 및 사용자 행위 추적(Tracking) 위험** |

#### 한줄 요약

- 중앙 DB 및 IdP 종속을 탈피하여 W3C 표준 규격에 따라 제어자가 직접 공개키와 검증 관계를 동적 통제

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C DID Core 1.0**: W3C의 분산 식별자 아키텍처 및 데이터 모델 최고 표준 권고안 명세
- **키 회전 (Key Rotation)**: 노출 위험 및 만료에 대비해 DID 문서 내 공개키를 안전하게 신규 키로 교체 갱신하는 절차
- **키 복구 (Key Recovery)**: 단말 비밀키 상실 시 사전 정의된 멀티시그 또는 사회적 복구(Social Recovery)로 제어권을 재획득하는 기법
- **쌍별 DID (Pairwise DID)**: 서비스별 전용 DID를 개별 생성하여 서비스 간 사용자 상관 추적을 원천 차단하는 프라이버시 보호 기법

</details>

| 장애 및 위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 이기종 저장소 간 DID 구문 및 문서 연동 실패 | 벤더사별 독자 구현으로 인한 식별자 해소 및 스키마 불일치 | **W3C DID Core 1.0** 글로벌 표준 규격 준수 및 공통 드라이버 도입 | 글로벌 식별자 해소 호환성 및 플랫폼 간 상호운용성 완전 확보 |
| 서비스 간 단일 DID 공유로 인한 상관 추적 피해 | 고정 식별자 재사용에 따른 검증자 간 사용자 프라이버시 침해 | 검증 대상별 가변 식별자를 부여하는 **쌍별 DID (Pairwise DID)** 적용 | 서비스 간 사용자 식별자 결합 추적 무력화 및 익명성 보장 |
| 단말 분실 및 암호키 노출에 따른 제어권 영구 상실 | 분산 환경 특성상 중앙 비밀번호 초기화 채널 부재 | 안전한 **키 회전(Key Rotation)** 및 분산 **키 복구(Key Recovery)** 메커니즘 구축 | DID 제어권 탈취 방지 및 개인키 분실 시 안전한 권한 회복 |

#### 한줄 요약

- W3C 표준 준수, 프라이버시 보호를 위한 Pairwise DID 적용, 비상시 제어권 유지를 위한 키 회전/복구 체계 구현

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DID 수용 조건 (DID Acceptance Criteria)**: DID 방법 신뢰성, 최신 문서 활성 여부, 공개키 검증 관계 적합성을 종합 심사하는 판단 기준

</details>

- 중앙 집중형 신원 체계의 데이터 독점과 프라이버시 침해를 해결하기 위해, **W3C DID Core 1.0** 표준에 기반하여 식별자 구문과 DID 문서 스키마를 정립하고, **방법 신뢰성·문서 활성화·키 용도 매핑**을 검증하는 **DID 수용 조건** 준수를 통해 글로벌 상호운용 가능한 분산 신원 생태계 구축 필수

#### 한줄 요약

- W3C DID 표준 기반의 식별자 해소 및 검증 관계 검증을 통한 자기주권 분산 신원 생태계 구현
