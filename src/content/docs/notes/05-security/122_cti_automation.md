## 미리 알고가기

- **CTI (Cyber Threat Intelligence)**: 공격 주체·행위·지표의 맥락과 근거를 분석해 방어 결정에 쓰는 정보
- **IoC (Indicator of Compromise)**: 악성 IP·도메인·파일 해시처럼 침해 관측과 헌팅에 쓰는 지표
- **TTP (Tactics, Techniques and Procedures)**: 공격자가 목표를 달성하는 전술·기법·절차
- **TIP (Threat Intelligence Platform)**: 여러 위협 피드를 정규화·평가·배포하는 플랫폼
- **STIX (Structured Threat Information Expression)**: 위협 객체와 관계를 기계가 읽을 수 있게 표현하는 표준
- **TAXII (Trusted Automated Exchange of Intelligence Information)**: STIX 기반 위협 정보를 서버 사이에서 교환하는 전송 규약
- **TLP (Traffic Light Protocol)**: 위협 정보의 재공유 가능 범위를 색상 등급으로 표시하는 규칙
- **OSINT (Open Source Intelligence)**: 공개 웹·보고서·데이터에서 수집한 위협 정보
- **시효**: 위협 지표가 현재 공격을 설명하는 데 유효한 기간
- **헌팅**: 자동 경고 없이 로그에서 공격 흔적을 능동적으로 찾는 활동
- **CTI·IoC·TTP 읽기**: “시티아이·아이오시·티티피”로 읽으며 위협정보·침해지표·공격 전술기법절차의 영문 머리글자임
- **STIX·TAXII·TLP 읽기**: “스틱스·택시·티엘피”로 읽으며 위협정보 표현·교환·공유등급 규칙의 영문 머리글자임
- **TIP·OSINT 읽기**: “팁·오신트”로 읽으며 위협정보 플랫폼과 공개출처 정보의 영문 머리글자임



## Ⅰ. 개요

- 정의/개념: 위협정보를 수집·정규화·평가해 방어 도구로 자동 배포하는 체계
- **배경/필요성**: 원시 위협 피드의 중복·만료·맥락 부족으로 직접 자동 대응 곤란

### 쉽게 이해하기 (학습용)

- 외부 공격 정보를 우리 자산과 시점에 맞춰 검증한 뒤 탐지나 차단에 사용함

## Ⅱ. 특징

- 의사결정 목적에 맞춰 위협 정보를 제공한다.
- 신뢰도·시효 보강이 실행 가능한 정보를 만든다.
- STIX 표현·TAXII 교환과 대응 결과로 정보 품질을 개선한다.

### 쉽게 이해하기 (학습용)

- 형식만 맞추지 않고 출처·시효·내부 자산 관련성을 함께 검증함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 수집 | OSINT·상용·공유 피드의 출처를 관리함 |
| 정규화 | 형식·시간을 맞추고 중복을 정리함 |
| 보강 | 신뢰도·시효·충돌 정보를 결합함 |
| 배포 | SIEM·EDR·SOAR로 정보 전달함 |
| 피드백 | 적중·오탐 결과를 피드백 기록함 |

```text
[OSINT·상용·공유 피드] → [TIP]
                            ├─ 정규화·중복 제거
                            ├─ 신뢰도·시효·자산 보강
                            └─ STIX로 표현·TAXII로 교환
                                      ↓
                         [SIEM·EDR·SOAR: 탐지·헌팅·차단]
                                      ↓ 적중·오탐
                                 [품질 갱신]
```

### 쉽게 이해하기 (학습용)

- IP의 시점·공격 관계·내부 사용 여부로 차단과 헌팅을 판단함

## Ⅳ. 원리 및 절차 흐름도

```text
수집 → 출처·형식 검증 → 신뢰도·시효·자산 보강 → 탐지 후 제한 차단 → 적중·오탐 갱신
```

| 절차 | 설명 |
|:---|:---|
| 요구 | 탐지 목표·신뢰 피드 조건을 정의함 |
| 수집 | 인증·스키마·출처를 검증함 |
| 정제 | 시효·자산 맥락으로 우선순위화함 |
| 배포 | 헌팅·경보·차단 순으로 배포함 |
| 갱신 | 적중·오탐으로 점수를 갱신함 |

### 쉽게 이해하기 (학습용)

- 새 피드는 먼저 탐지용으로 검증하고 신뢰도가 확인된 지표만 제한적으로 자동 차단함

## Ⅴ. CTI 자동화 요소 비교

| 비교축 | STIX 2.1 | TAXII 2.1 | TIP |
|:---|:---|:---|:---|
| 적용 기준 | 기계 판독 형식을 통일할 때 | 조직·플랫폼 간 정보를 전송할 때 | 출처·시효·중복·배포를 운영할 때 |
| 핵심 특징 | 위협 객체·관계를 표현 | 위협 정보를 API로 교환 | 여러 피드를 평가·배포 |
| 한계 | 부정확한 객체 관계 전파 | 인증·공유 범위 설정 오류 | 낮은 품질 피드가 자동 차단으로 확산 |

> 요약: 표준 준수와 효율적 피드 관리 수행함

### 쉽게 이해하기 (학습용)

- 표준 형식과 전송이 맞아도 내용이 오래됐거나 틀리면 TIP에서 걸러야 함

## Ⅵ. 실무 사례

1. 악성 IP의 **시간·행위 맥락 검증 후 자동 차단**

### 쉽게 이해하기 (학습용)

- CTI로 받은 악성 IP는 공격 시점·행위·자사 사용 여부·신뢰도를 검증하고 만료일과 롤백을 포함한 방화벽 정책으로 배포한다.

## Ⅶ. 결론

- 위협 정보 자동화의 오차단과 정보 오용을 막기 위해 출처·신뢰도·맥락·TLP·유효기간·롤백을 검토하여, 검증된 CTI만 탐지·헌팅·차단에 배포해야 한다.

### 쉽게 이해하기 (학습용)

- 자동화 속도보다 틀리거나 오래된 위협 정보가 차단 명령으로 번지지 않게 하는 것이 중요함
