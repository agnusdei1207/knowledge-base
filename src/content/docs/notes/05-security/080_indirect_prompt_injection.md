## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **간접 프롬프트 인젝션 (Indirect Prompt Injection)**: 사용자가 직접 입력하지 않고 외부 웹사이트, 이메일, PDF 문서, RAG 지식베이스에 미리 은닉된 악성 프롬프트 텍스트가 LLM 수용 시 자동 해석되어 비인가 동작을 유도하는 공격 기법이다.
- **신뢰 경계 붕괴 (Trust Boundary Collapse)**: 외부 비신뢰 데이터(웹/문서)가 RAG 또는 외부 API를 통해 LLM 내부 문맥으로 유입되면서 안전한 신뢰 데이터와 비신뢰 데이터의 보안 경계가 무너지는 현상이다.

</details>

- 정의: LLM이 참고하는 외부 데이터 원천에 공격 지시를 은밀히 매복시켜, 사용자가 의도치 않게 LLM을 통해 공격자의 악성 명령을 실행하도록 조종하는 지향 해킹 기법이다.
- 배경: LLM이 RAG(검색 증강 생성)나 웹 검색을 통해 수집한 외부 콘텐츠를 신뢰 가능한 제어 지침으로 무비판적으로 수용하여 발생하는 신뢰 경계 붕괴 현상 때문이다.

#### 한줄 요약

- 외부 데이터 원천에 은닉된 악성 지시를 통해 LLM 제어권을 무단 탈취하고 비인가 조작을 유도하는 공격 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **RAG 유입 (Retrieval-Augmented Generation Ingress)**: 외부 벡터 DB에서 검색된 텍스트 조각(Chunk)에 포함된 인젝션 구문이 정상적인 검색 결과인 것처럼 LLM 프롬프트에 주입되는 유입 경로이다.
- **다중모달 유입 (Multimodal Ingress)**: 텍스트뿐만 아니라 OCR 이미지, 오디오 스테가노그래피 내에 악성 프롬프트를 은닉하여 멀티모달 LLM으로 유입시키는 은밀한 경로이다.
- **지연 발동 (Dormant / Delayed Execution)**: 데이터 수집 및 색인 시점에는 발동하지 않다가 특정 키워드 질문이나 RAG 조건이 성립될 때 비로소 악성 명령이 실행되는 지연형 공격 특성이다.
- **독립 권한 검증 (Independent Authorization Verification)**: LLM의 추론 결과를 전적으로 신뢰하지 않고, 별도의 독립 PEP 정책 엔진이 최종 사용자의 IAM 최소 권한 및 파라미터를 재차 검증하는 통제 기법이다.

</details>

- **비대면 스텔스 유입**: 사용자가 인지할 수 없는 **RAG 유입** 및 **다중모달 유입**(이미지, 음성)을 통해 우회적으로 공격이 침투한다.
- **시한폭탄형 지연 발동**: 악성 데이터 적재 즉시 실행되지 않고, 특정 문맥 검색 시 호출되는 **지연 발동** 기법을 사용하여 사전 탐지가 매우 어렵다.
- **독립 검증 방어 필수**: LLM 내부 필터링의 한계를 보완하기 위해 출력 결과를 독립적으로 검증하는 **독립 권한 철저한 검증** 및 샌드박스 인프라를 강제한다.

#### 한줄 요약

- RAG/다중모달을 통한 은닉 유입, 탐지가 어려운 지연 발동 특성 및 독립 권한 검증 샌드박스 기반 방어 체계를 지닌다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ACL (접근 제어 목록 / Access Control List)**: RAG 파이프라인에서 원천 문서의 보안 등급과 접근 권한을 텍스트 조각(Chunk) 단위로 결속 추적하는 보안 정책이다.
- **출처 보존 (Provenance Preservation)**: 수집된 외부 데이터의 URL, 생성자, 수집 경로, 변경 이력을 텍스트 메타데이터로 원본 보존하는 추적 관리 기술이다.
- **정책 게이트웨이 (Policy Gateway / PEP)**: LLM이 도출한 API 호출(Tool Call)이 실제 사용자의 권한 범위를 초과하는지 체크하는 독립 보안 솔루션이다.

</details>

```text
[간접 프롬프트 인젝션 철저한 방어 체계]
                  |
                  +-- [1. 외부 콘텐츠 사전 정제 및 수집]
                  +-- [2. RAG 문서 권한(ACL) 및 출처 보존]
                  +-- [3. 시스템 지침과 검색 문맥 태그 완전 격리]
                  +-- [4. 안전 정렬 기반 LLM 모델 응답 제안]
                  `-- [5. 독립 정책 게이트웨이 최종 인가 철저한 검증]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **외부 콘텐츠 수집** | 웹, 이메일, PDF 내 악성 텍스트 사전 정제 및 **다중모달 유입** 스캐닝 | Ingestion |
| **권한 및 출처 보존** | 검색 데이터에 원본 **ACL** 및 **출처 보존** 메타데이터 결속을 통한 권한 승격 차단 | Provenance |
| **검색 문맥 완전 격리** | RAG 탐색 결과를 시스템 지침과 명확히 구분되도록 XML/JSON 태그로 완전 격리 | Context Isolation |
| **모델 응답 제안** | LLM이 탐색 문맥을 바탕으로 사용자 응답 텍스트 및 외부 API Tool Call 제안 생성 | LLM Inference |
| **정책 게이트웨이** | **정책 게이트웨이** 활용 거쳐 Tool Call 인자값의 안전성 및 사용자 IAM 2차 철저한 검증 | Enforcement |

#### 한줄 요약

- 외부 데이터 정제, ACL 기반 출처 보존, RAG 태그 격리 및 정책 게이트웨이 2차 인가 검증으로 신뢰 경계를 확립한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **거래 결속 (Transaction Binding)**: 사용자가 최초 요청한 파라미터(이메일 수신자, 이체 금액 등)를 세션에 고정하여 간접 인젝션에 의한 파라미터 무단 조작을 방지하는 기술이다.
- **사용자 승인 (Human-in-the-Loop)**: 데이터 삭제, 이체 등 외부 상태 변경(State Change)을 야기하는 Tool Call 실행 전 사용자 팝업 승인을 구하는 방식이다.
- **외부 통신 통제 (Egress Control)**: 에이전트 시스템이 허용된 화이트리스트 도메인 외에 공격자 C2 서버로 접속하는 것을 네트워크 레벨에서 차단하는 통제이다.

</details>

```text
[인터넷 상의 공격 지시 은닉 문서]
                  |
                  v
1. 외부 콘텐츠 수집 및 벡터 DB 색인
                  |
                  `-- 악성 프롬프트가 매복된 비신뢰 문맥
                              |
                              v
2. LLM 내부 데이터 및 제어 지침 경계 혼동
                              |
                              v
3. 특정 질문에 매칭 시 지연 공격 지시 활성화 발동
                              |
                              `-- 조작된 응답 및 외부 API 도구 호출 제안
                                          |
                                          v
[독립 정책 게이트웨이 및 Egress 통제 부재 시]
                                          |
                                          v
4. 독립 권한 대조 및 거래 결속 검증 절차 누락
                                          |
                                          `-- 악의적으로 변조된 과도한 권한의 도구 호출
                                                      |
                                                      v
                                          5. 비인가 외부 전송(C2 유출) 및 상태 변경 실행
                                                      |
                                                      v
                                          [치명적 기밀 유출 및 시스템 조작 결과 발생]
```

### 동작 원리

1. 수집 및 매복: 외부 사이트 수집 시 숨겨진 악성 지시가 RAG DB에 저장된다.
2. 지침 경계 혼동: 사용자의 검색으로 호출된 비신뢰 문서를 LLM이 제어 지침으로 착각한다.
3. 지연 활성화: 조건 충족 시 매복된 악성 프롬프트가 데이터 반출 등의 액션을 지시한다.
4. 독립 검증 누락: PEP 등의 권한 검증 절차 없이 조작된 API 호출이 그대로 수용된다.
5. 시스템 침해 실행: 인가되지 않은 기밀 데이터 유출 및 시스템 상태 변조가 실행된다.

#### 한줄 요약

- 매복 데이터 색인, 지침 혼동, 지연 명령 활성화, 정책 게이트웨이 검증 누락 및 무단 데이터 반출로 피해가 확산된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **직접 인젝션 (Direct Prompt Injection)**: 사용자가 프롬프트 입력창을 통해 지침 무효화 명령을 직접 주입하는 명시적 공격이다.
- **읽기 전용 에이전트 (Read-only Agent)**: 외부 시스템의 데이터 단순 조회만 허용되며, 시스템의 상태 변경(Write/Delete) 권한이 전혀 없는 안전한 에이전트이다.
- **행동 에이전트 (Action Agent / Autonomous Agent)**: 이메일 발송, DB 수정, 결제 등 외부 시스템의 상태 변경(State Change)을 자율적으로 수행하는 고위험 에이전트이다.

</details>

| 프롬프트 공격 및 에이전트 특성 | **간접 프롬프트 인젝션** | **직접 프롬프트 인젝션** | **읽기 전용 에이전트 vs 행동 에이전트 연동 시 영향** |
|:---|:---|:---|:---|
| 주요 침투 경로 | 외부 RAG 문서, 서드파티 웹, 수신 이메일, PDF | 사용자가 텍스트를 입력하는 직접 대화창 | 에이전트에 부여된 시스템 권한 범위에 완전 종속됨 |
| 주 공격 주체 | 비인가 제3자 (매복 문서 작성자) | 해당 서비스를 이용 중인 악의적 사용자 | 방어 대상 위협 시나리오에 따라 다름 |
| 피해 파급력 | **행동 에이전트 연동 시 심각한 C2 유출 및 조작** | 시스템 프롬프트 무단 유출, 윤리 필터 우회 | **행동 에이전트** 경우 무단 이체/삭제 등 치명적 조작 위험 노출 |
| 핵심 방어 기술 | **RAG 문서 태그 격리, 정책 게이트웨이, 외부 통신 통제** | XML 입력 데이터 물리적 분리, LLM WAF 가드레일 | **최소 권한 원칙**, **사용자 서명 승인**, **거래 결속** |

#### 한줄 요약

- 간접 인젝션은 제3자 매복 데이터 기반 공격이며, 행동 에이전트와 연동될 경우 심각한 시스템 무단 조작 파급된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OWASP LLM01:2025**: 글로벌 보안 표준 기구 OWASP가 발표한 LLM 1위 위험 항목으로, 프롬프트 인젝션 내 간접 인젝션 방어 규격이다.
- **MITRE ATLAS AML.T0051.001**: MITRE ATLAS에 등록된 간접 프롬프트 인젝션 공격 기술 고유 식별 코드이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| **간접 인젝션을 통한 비인가 데이터 외부 반출 사고** | 에이전트의 외부 아웃바운드 접속 정책 미비 | **OWASP LLM01:2025** 기준 적용 및 **비인가 외부 통신 통제(Egress)** | 화이트리스트 외 공격자 C2 서버로의 기밀 데이터 반출 원천 무력화 |
| **간접 AI 공격 기법에 대한 시그니처 관리 부재** | 다양한 매복 공격 우회 기법 대응력 부족 | **MITRE ATLAS AML.T0051.001** 매핑 체계 정립 | 간접 인젝션 TTPs 기반의 LLM WAF 룰 세트 정립 및 상시 모니터링 |
| **에이전트에 의한 외부 API 무단 실행 및 상태 조작** | 제안된 Tool Call을 맹목적 자동 실행 | **거래 결속** 보장, **사용자 재승인 (Human-in-the-Loop)** 절차 강제 | LLM이 악성 명령에 속더라도 최종 자산 변경 전 관리자 승인으로 철벽 차단 |

#### 한줄 요약

- OWASP LLM01:2025 및 ATLAS 표준을 준수하고, 엄격한 외부 통신(Egress) 통제 및 Human-in-the-Loop 조치를 수립한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **권한 전이 차단 (Privilege Escalation & Transfer Containment)**: 외부 비신뢰 데이터가 LLM을 거쳐 해석되더라도, 원래 문서가 가진 권한을 초과하여 사용자의 인가 권한으로 비정상 승격 전이되지 않도록 방화벽을 치는 보안 원칙이다.

</details>

- 간접 프롬프트 인젝션의 은밀한 매복 위험을 통제하기 위해, 조회 업무는 **읽기 전용 에이전트** 기반 국한시키고, 시스템 상태 변경 업무는 철저한 **사용자 재승인** 및 **권한 전이 원천 차단** 보장하는 Zero Trust 체계 확립 필수이다.

#### 한줄 요약

- RAG 문맥 태깅 격리, 런타임 정책 게이트웨이 및 권한 전이 원천 차단 중심의 간접 인젝션 방어 아키텍처 구축 필수.
