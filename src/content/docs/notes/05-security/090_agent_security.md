## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **에이전트 보안 (Agent Security)**: 읽기 위주의 단순 대화형 텍스트 LLM 챗봇 수준을 완전히 뛰어넘어, 인간의 개입 없이 자율적으로 다단계 실행 계획(Planning)을 세우고 외부 위험 도구(이체 API, 핵심 DB 쿼리, 운영 OS Command)를 스스로 트리거하여 실행해 버리는 AI 자율 에이전트의 권한 과다(Excessive Agency) 남용, 치명적 비인가 시스템 파괴 조작, 그리고 무한 도구 루프에 의한 연쇄 과금 폭주를 물리적으로 방어 차단하는 통제 아키텍처 특징이다.
- **출력과 행동의 본질적 차이 (Output vs. Action Distinction)**: 잘못된 문장 한 줄 뱉어내고 끝나는 단순 텍스트 응답 오류 출력(Output)과 달리, 외부 시스템 인프라의 실제 불가역적 상태 변경(State Modification: 예- 거액 자동 결제, 고객 원장 파일 영구 삭제, 악성 메일 수만 통 발송)을 직통으로 야기하는 자율 에이전트 특유의 파괴적 위험 차이점 특징이다.

</details>

- 정의: AI의 위험한 도구 자동 호출 능력과 물리적 서버 상태 변경(State Modification) 권한을 게이트웨이 레벨에서 강력히 틀어막고 통제하는 **자율 에이전트 전용 방어 보안 체계**이다.
- 배경: 과거의 가벼운 텍스트 환각 오류가 이제는 곧바로 실제 기업 자산 파괴(DB 삭제, 이체) 오류로 직결되는 무서운 **출력과 행동의 본질적 차이** 시대가 도래하여 치명적 권한 사고가 빈발하고 있기 때문이다.

#### 한줄 요약

- 인간 개입 없이 자율적 외부 툴 실행과 물리적 상태 변경을 직접 야기하는 AI 에이전트의 비인가 파괴 시스템 조작 및 과도한 대리 권한 오남용을 원천 통제하는 철벽 보안 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **완전 매개 (Complete Mediation)**: 에이전트가 내뱉는 모든 위험천만한 도구 호출(Tool Call) 외부 요청을 PEP(정책 집행) 게이트웨이가 100% 단 한 건의 바이패스 예외도 없이 전면 인터셉트하여 인가 여부를 2차 크로스 체크 검증해 내는 무관용 보안 원칙이다.
- **최소 권한 (Least Privilege)**: 에이전트가 마치 어드민(Admin)인 것처럼 날뛰지 못하도록, 부여된 단일 과업 수행에 딱 필요로 하는 최소한의 최적 API 기능 및 초소형 읽기/쓰기 스코프(Scope) 권한만을 제한적으로 부여하는 족쇄 인가 원칙이다.
- **제한 토큰 (Scope-bounded / Ephemeral Tokens)**: 에이전트가 툴 호출 인증 시 사용자의 막강한 마스터 전체 권한을 통째로 넘겨받는 것이 아니라, 특정 1회성 목적 작업과 불과 몇 분짜리 초단기 수명(TTL)만을 부여받은 외부 래퍼 OAuth/API 임시 토큰 특징이다.
- **보상 동작 (Compensating Action / Saga Pattern)**: 에이전트가 연쇄 API 작업 도중 치명적 에러나 환각 공격에 노출되어 실패했을 때, 이미 중간 집행 완료되어 버린 외부 시스템의 상태 변경을 원상태로 깔끔히 되돌려 놓는 취소/원복 롤백 트랜잭션 기법이다.

</details>

- **Zero Trust 비신뢰 격리 취급**: 공격에 오염되기 쉬운 에이전트가 임의로 생성한 추론 계획서와 호출하려는 도구 인자값을 100% 비신뢰(Zero Trust) 위험 객체 취급하여 격리 검증한다.
- **게이트웨이 무관용 통제 및 족쇄**: 보안망 최전선의 **완전 매개** 인터셉트 원칙 및 철저한 **최소 권한** 기반 초단기 **제한 토큰** 강제 발급 적용하여 에이전트의 과도한 자율 권한 폭주를 원천 원천 차단한다.
- **비가역 액션 팝업 차단 및 롤백**: 데이터 삭제 등 고위험 비가역 실행 직전 반드시 인간에게 팝업 승인(Human-in-the-Loop)을 강제하며, 연쇄 장애 발생 시 **보상 동작** 통한 롤백 원복으로 시스템 파괴 잔여 손상 피해를 최소화한다.

#### 한줄 요약

- 추론 제안값 100% 비신뢰 격리, 완전 매개 룰 및 최소 권한 제한 토큰 부여, Human-in-the-Loop 인간 팝업 개입 및 보상 동작 원복 특성을 지닌다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **도구 등록부 (Tool Registry / Schema Store)**: 무차별 API 호출을 막기 위해, 에이전트가 오직 제한적으로 호출할 수 있도록 화이트리스트 검증된 외부 API 함수 목록, 엄격한 파라미터 규격 스키마, 그리고 기능별 파괴 위험 등급(High/Low Risk)을 등록 관리하는 핵심 레포지토리이다.
- **PEP (Policy Enforcement Point)**: 환각에 빠진 LLM 에이전트가 멋대로 도출해 낸 Tool Call 실행 요청이, 실제 해당 사용자가 보유한 IAM 최소 권한 범위 및 사전에 약속된 파라미터 유효성 한계 기준에 정확히 적합한지를 런타임에 냉혹하게 심사 커트하는 통제 관문이다.
- **감사 계층 (Audit Trail / Traceability Layer)**: 에이전트가 최초 프롬프트를 수신한 순간부터, 내부 판단 추론, 툴 호출 집행, 반환 결과값, 그리고 최종 외부 상태 변경 이력 전체를 해커가 조작할 수 없는 비가역 해시 감사 로그로 영구 기록 보존하는 감시 계층이다.
- **복구 계층 (Recovery & Rollback Layer)**: 5단계 연쇄 툴 실행 중 3단계에서 에이전트 오판 에러나 프롬프트 인젝션 공격 징후 감지 시, 앞서 실행된 1, 2단계의 상태를 이전 안전 백업 스냅샷 상태로 즉각 롤백 취소 조치해 내는 계층이다.

</details>

```text
[자율 실행 에이전트 통제 아키텍처 및 무결성 철저한 방어선]

├─ [1. 사전 요청 및 격리 계획 경계]
│    ├─ [신원 및 최소 권한 위임 계층] (제한 토큰 발급)
│    └─ [비신뢰 추론 계획 및 작업 메모리 샌드박스 계층]
│
├─ [2. 실시간 런타임 툴 실행 통제 경계]
│    ├─ [화이트리스트 도구 등록부] (스키마 및 위험 등급 규격 대조)
│    └─ [정책 집행점 (PEP)] (완전 매개 게이트웨이 파라미터 차단)
│
└─ [3. 사후 롤백 및 불변 감사 경계]
     ├─ [비가역 추적 감사 증적 계층] (모든 행위 해시 로그 보존)
     └─ [트랜잭션 취소 롤백 복구 계층] (Saga 패턴 연쇄 원복 가동)
```

| 통제 보호 레이어 | 핵심 방어 구성 요소 | 주요 타격 방어 기능 및 역할 |
|:---|:---|:---|
| **사전 요청 및 계획 경계** | 신원/위임 인증 계층, 계획/단기 메모리 계층 | 사용자 신원 IAM 인증, 초단기 수명의 1회성 **제한 토큰** 철저 발급 및 오염 위험이 높은 비신뢰 메모리/프롬프트 영역 물리 완전 격리 |
| **런타임 툴 실행 경계** | **화이트리스트 도구 등록부**, **PEP** (정책 집행점 게이트웨이) | **도구 등록부** 화이트리스트 스키마 대조 락, **PEP** 철벽 관문을 통과해야만 Tool Call 인자값 및 사용자 최소 권한 2차 대조 집행 |
| **사후 원복 및 감사 경계** | 비가역 **감사 계층**, 트랜잭션 **복구 계층** | 해커 조작이 불가능한 비가역 **감사 계층** 추적 로그 블록체인 저장, 에러 시 **보상 동작** 이용한 연쇄 도구 실행 **복구 계층** 롤백 작동 |

#### 한줄 요약

- 요청/계획망 경계(제한 토큰 족쇄), 강력한 실행 통제 경계(도구 등록부, PEP 관문) 및 사후 원복 경계(불변 감사 계층, 롤백 복구 계층)로 철벽 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **거래 결속 (Transaction Binding)**: 악성 에이전트가 중간에 값을 빼돌리지 못하도록, 사용자가 최초 요청 시 직접 팝업 승인한 원본 파라미터(예: 송금 수신자 계좌, 이체 확정 금액, 삭제 지정 대상 객체 등)를 런타임 세션에 암호학적으로 결속(Binding)하여, 도구 실행 시 에이전트가 절대 다른 인자로 임의 조작하지 못하게 동결 락을 거는 보안 기술이다.
- **단계 중단 (Step-wise Interruption / Execution Halt)**: 5번의 다단계 연쇄 툴 실행 집행 도중, 특정 3번째 단계에서 치명적 에러 코드나 인젝션 이상 행동 징후가 감지될 시 뒤이은 4, 5단계 집행을 0.1초 만에 즉각 셧다운 정지시켜 피해 확산을 막는 차단 관문이다.

</details>

```text
[사용자의 작업 목적 제출 및 최소 권한 한도 부여]
                  |
                  v
1. 에이전트의 LLM 자율 실행 계획서 및 도구 API 호출 후보 인자값 생성
                  |
                  v
[고위험 상태 변경 행동 감지 시 Human-in-the-loop 재승인 팝업 노출]
                  ├── (거부/타임아웃) ──> 전체 실행 즉각 중단 폐기
                  |
               (인간 승인)
                  v
2. 승인된 원본 파라미터와의 강력한 거래 결속(Binding) 및 PEP 정책 한계 대조 검증
                  |
                  v
3. 초단기 1회성 제한 토큰(Scope-bounded Token)만 쥐여주고 샌드박스 내에서 툴 격리 실행
                  |
                  v
4. 외부 API 실행 후 반환된 응답 상태값 무결 검증 및 비가역 불변 감사 증적 시스템 해시 로그 저장
                  |
                  ├── (성공) ──> 최종 과업 완료 및 실행 결과 사용자 리포트 반환
                  |
                  └── (실패/공격 징후) ──> 5. 연쇄 단계 즉각 중단 및 이전 트랜잭션 상태로 취소·보상(Saga) 롤백 원복 처리
                                                 |
                                                 v
                                        [손상 전 원상 복구 및 위험 차단 결과 알림]
```

### 동작 원리

1. 도구 제안 생성: LLM 에이전트가 목표 달성을 위한 위험한 다단계 실행 계획 및 API 호출 후보 파라미터를 일단 생성한다.
2. 인간 승인 및 결속 검증: 고위험 액션 전 인간 팝업 승인을 받고, 원본 인자값과 PEP 보안 정책을 락(Lock) 거래 결속 대조한다.
3. 제한 토큰 격리 실행: 마스터 키가 아닌 오직 수분짜리 1회성 임시 토큰만 발급하여 철창 샌드박스 안에서 툴을 실행시킨다.
4. 상태 검증 및 해시 감사: 실행 반환 결괏값을 독성 검증하고 비가역적 해시 감사 시스템에 로그 이력을 보존한다.
5. 롤백 취소 보상 처리: 해킹이나 에러로 단계 실패 시 전체 프로세스 중단 및 즉각적인 상태 원복 보상 트랜잭션을 집행한다.

#### 한줄 요약

- 도구 제안 생성, Human-in-the-Loop 인간 팝업 승인, 락업 거래 결속 및 PEP 검증, 제한 토큰 샌드박스 실행, 감사 저장, 실패 시 롤백 취소/보상 원복 단계로 이행된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **일반 챗봇 (Conversational Chatbot)**: 오직 텍스트 문장과 자연어 대화 응답만을 도출해 낼 뿐, 외부 시스템 데이터를 파괴하거나 주문 상태를 변경할 수 있는 치명적 권한(State Modification)이 원천적으로 하나도 없는 가장 안전한 텍스트 생성 전용 Read-Only 장난감 모델이다.
- **RAG 서비스 (Retrieval-Augmented Generation)**: 외부 벡터 지식베이스 검색 쿼리를 던져 사내 규정 데이터를 읽어와 프롬프트 문맥으로 단순 조합해 정밀 응답을 도출해 내는, 읽기 특화형 아키텍처 특징이다.
- **도구형 자율 에이전트 (Tool-augmented Autonomous Agent)**: 단순 텍스트 조회를 넘어, 외부 클라우드 결제 API, 핵심 DB의 Delete/Update, 리눅스 OS Shell 스크립트 실행 등 치명적 변경 인가 권한을 양도받아 자율적으로 시스템 생사여탈 액션을 집행하는 프로세서 AI 애플리케이션이다.

</details>

| AI 아키텍처 생태계 유형 구분 | **단순 일반 챗봇 (Conversational Chatbot)** | **사내 검색 RAG 서비스 (Retrieval-Augmented)** | **무한 행동력 도구형 에이전트 (Autonomous Agent)** |
|:---|:---|:---|:---|
| 시스템의 핵심 목적 및 지향 기능 | 대화 자연어 텍스트 문장 조합 및 감성 챗 응답 텍스트 무해 생성 | 사내 벡터 DB 조회를 통한 환각 억제 및 사규/지침 기반 정밀 텍스트 도출 | 치명적 외부 유료 API, 운영 DB 변경, 서버 OS 파이썬 명령문 자율 집행 타격 |
| 파생되는 치명적 주요 보안 위험 요소 | 고전적 프롬프트 인젝션 언어 공격, AI 윤리 가이드 위반, 단순 PII 노출 | 엉뚱한 RAG 문서 오염(Poisoning), 간접 인젝션(Indirect), 벡터 ACL 열람 권한 누락 | 과도한 대리권 부여 마비(**LLM06**), 제어 불능 비인가 런타임 시스템 상태 파괴 조작 |
| 최우선 핵심 방어 포인트 통제 | 지시어 XML 프롬프트 철저 격리, LLM Input/Output WAF 검열 필터 정제 | 검색 RAG 벡터 ACL 사용자 권한 1:1 동기화, 검색 출처 메타데이터 무결성 역검증 | 철벽 **PEP 게이트웨이** 관문, 철창형 **제한 토큰**, 비가역 비상시 **인간 최종 재승인(Human)** |
| 외부 시스템의 영구 상태 변경 조작 여부 | 전혀 없음 철벽 방어 (100% 무해 Read-Only 텍스트 출력 한정) | 전혀 없음 (오직 100% 사내 문서 탐색 Read-Only 조회 텍스트 출력 한정) | 치명적 있음 (DB 삭제 등 실제 운영 서버의 불가역적 **State Modification** 자율 집행) |

#### 한줄 요약

- 안전한 단순 챗봇(대화 텍스트 전용), RAG(사내 검색 조회 전용), 치명적 도구형 에이전트(외부 자율 상태 영구 변경 집행)로 구분되며, 이 중 에이전트는 PEP 및 단기 제한 토큰 통제가 목숨처럼 필수적인 특징이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **LLM06:2025 (OWASP Top 10 Excessive Agency)**: 자율 에이전트에게 팝업 승인 통제 없이 과도한 과업 자율 실행 권한이 통째로 맹목적 위임되어 발생하는 참사를 경고한 OWASP 2025 핵심 치명적 위험 규격이다.
- **샌드박스 격리망 (Sandbox / Runtime Isolation)**: AWS Firecracker나 Google gVisor 등 초경량 마이크로VM 인프라를 활용하여, 해킹당한 에이전트가 뿜어내는 악성 파이썬 코드/OS 시스템 명령어를 본진 클라우드와 완벽히 물리적으로 단절 격리된 폐쇄 철창 속에서만 집행하여 본서버 파괴를 막는 인프라 보호 기술이다.
- **AI 600-1 (NIST Generative AI Profile, AI 600-1)**: 에이전트 시스템 배포 시 인간의 상시 감시 통제(Human Oversight) 및 코드 샌드박싱 방어 지침을 의무 조항으로 명시한 미국 국립표준기술연구소의 지침이다.
- **사용자 재승인 관문 (User Re-approval / Human-in-the-Loop)**: 고액 금융 이체, 운영 DB 테이블 삭제, 전체 고객 대상 메일 대량 발송 등 주워 담을 수 없는 비가역적 파괴 액션 실행 직전, 에이전트의 독단을 멈춰 세우고 반드시 인간 관리자의 최종 OTP/서명 동의 버튼 팝업 클릭을 강제로 요구하는 방어 절차이다.

</details>

| 장애/위험 사고 요소 | 원인 분석 | 실무 대책 및 보안 해결방안 | 기대 방어 방파제 효과 |
|:---|:---|:---|:---|
| **해킹된 에이전트의 과도한 자율 권한 위임에 따른 파괴 사태** | 편의주의로 인한 어드민 마스터 권한의 에이전트 맹목 위임 | 글로벌 **OWASP LLM06:2025** 및 **NIST AI 600-1** 지침 전면 준용 | 무관용 원칙에 입각한 에이전트 권한의 극단적 최소화(Least Agency) 거버넌스 수립 달성 |
| **인젝션 유도 비인가 툴 API 맘대로 호출에 따른 클라우드 상태 파괴 변조** | 인자값 조작을 막는 잠금장치 결속 및 PEP 검문소 관문 부재 | 원본 파라미터 **거래 결속(Binding)**, **PEP** 철벽 게이트웨이 및 **사용자 팝업 재승인** 강제 | 고위험 액션의 에이전트 독단적 즉시 이행 원천 차단 및 필수 인간 감독(Human Oversight) 개입 시간 확보 |
| **프롬프트 해킹 파이썬 코드/리눅스 명령어 직접 실행 시 사내 인프라 전면 탈취 침해** | 본진 클라우드 OS 위에서 날것 그대로의 악성 쉘 스크립트 실행 허용 | 마이크로VM **샌드박스** (Firecracker/gVisor) 완벽 물리 격리 및 외부 Egress 통신 아웃바운드 차단 | 비인가 해킹 에이전트의 해커 C2 서버 연결 및 사내 본진 시스템 연쇄 파괴 감염 원천 차단 |

#### 한줄 요약

- OWASP LLM06:2025 위협 및 NIST AI 600-1 지침 철저 준수, 거래 파라미터 락 결속, PEP 검문 관문, 비가역 Human-in-the-Loop 팝업 차단 및 샌드박스 물리 격리를 전면 수립한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가역성 기반 승인 통제 기준 (Reversibility-based Authorization Criteria)**: 툴 실행의 파괴적 가역성(단순 조회로 인한 100% 원복 가능 여부 등) 및 데미지 위험도 등급에 따라, 저위험 조회는 자동 실행을 허용하되 고위험 비가역적 변경(결제, 삭제)은 무조건 인간 승인을 강제 차등 적용하는 유연하면서도 철저한 보안 가버넌스 통제 원칙이다.

</details>

- 모든 도구를 막을 수는 없으므로, **가역성 기반 승인 통제 기준** 원칙을 세워 가역적 데이터 조회 작업은 **초단기 제한 토큰** 기반으로 효율적 자동화를 허용하고, 복구 불능의 비가역적 영구 변경 액션은 런타임 **거래 결속 락** 및 인간의 최종 **사용자 팝업 재승인** 관문을 철벽 적용하는 것이 필수이다.

#### 한줄 요약

- 글로벌 OWASP LLM06/NIST AI 600-1 기준 준수, 엄격한 PEP 통제 관문, 1회성 제한 토큰, 샌드박스 격리, Human-in-the-Loop 개입 및 가역성 기반 승인 등급 중심 자율 에이전트 보안 체계 철벽 구축 필수.
