## 미리 알고가기

- **에이전트 (Agent)**: 계획 및 도구 호출 수행
- **가드레일 (Guardrail)**: 입력·출력·행동 제한
- **거대 언어 모델 (Large Language Model, LLM)**: 에이전트의 계획·생성 담당
- **검색 증강 생성 (Retrieval-Augmented Generation, RAG)**: 생성 문맥에 검색 결합
- **최소 권한 (Least Privilege)**: 도구 권한을 제한적으로 부여
- **제한 토큰**: 특정 작업·대상·시간에만 유효하도록 범위를 줄인 일회성 접근 자격
- **정책 집행점**: 도구 호출 직전에 주체·동작·대상·조건을 검사해 허용·거부하는 통제 지점
- **보상 동작**: 이미 실행된 작업을 취소할 수 없을 때 반대 작업으로 결과를 되돌리는 처리
- **샌드박스**: 코드·도구 실행이 실제 시스템에 미치는 영향을 제한하는 격리 환경



## Ⅰ. 개요

- 정의/개념: 에이전트의 **계획·도구 호출·권한·결과를 실행 시 통제**
- **배경/필요성**: 출력 필터만으로는 **외부 상태 변경·연쇄 실행 피해 방지 불가**

### 쉽게 이해하기 (학습용)

- 에이전트는 버튼을 누르는 작업자이므로, 필터보다 신원·권한·실행 결과 검사가 중요함

## Ⅱ. 특징

- **계획·메모리·도구 결과를 비신뢰 입력**으로 취급한다.
- **호출별 정책 집행·제한 토큰·사용자 승인**으로 권한을 완전 매개한다.
- **단계·시간·비용 한도와 취소·보상 동작**으로 잔여 피해를 제한한다.

### 쉽게 이해하기 (학습용)

- 시작 때 한 번이 아닌, 행동마다 재검사 필요

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 신원·위임 계층 | **요청자 권한을 제한 토큰으로 전달** |
| 계획·메모리 계층 | **비신뢰 데이터 격리·검사** |
| 도구 등록부 | **기능·스키마·위험·대상 관리** |
| 정책 집행점 | **호출별 주체·동작·대상 검증** |
| 감사·복구 계층 | **계획·승인·결과·보상 연결** |

```text
[권한 통제 구조]
 신원 위임 : 제한 토큰 기반 권한 위임
 계획 메모리 : 비신뢰 데이터 격리·검사
 도구 등록 : 기능·위험도·허용 대상 관리
 정책 집행 : 주체·동작·대상별 실시간 검증
 감사 복구 : 실행 결과 기록 및 취소·보상
```

> 요약: 모델은 제안하고 정책 집행점이 권한을 판단한다

### 쉽게 이해하기 (학습용)

- 모델은 행동을 제안하고 정책 집행점이 실제 권한을 최종 판단한다.

## Ⅳ. 원리 및 절차 흐름도

```text
범위확인
↓
계획생성
↓
정책검증
↓
결과승인
↓
실행복구
```

| 절차 | 설명 |
|:---|:---|
| 범위확인 | 사용자·목적·도구·단계 한도 정함 |
| 계획생성 | 도구 순서와 인수를 비신뢰 제안으로 생성 |
| 정책검증 | 권한·대상·누적 영향·형식 검증 |
| 결과승인 | 전송·삭제·결제 결과 사전 확인 |
| 실행복구 | 제한 토큰으로 실행·기록·취소 |

> 요약: 비신뢰 계획을 호출별 검증·승인해 실행·복구한다

### 쉽게 이해하기 (학습용)

- 도구 호출마다 결과 확인 및 실패 시 복구 기록

## Ⅴ. 종류 및 비교

| AI 응용 실행 범위 | 도구형 에이전트 | 일반 챗봇 | RAG 서비스 |
|:---|:---|:---|:---|
| 적용 기준 | 호출별 권한 검증·복구 | 입력·출력 위험 검증 | 문맥 격리·권한 인지 |
| 핵심 특징 | 도구 호출·외부 상태 변경 | 텍스트 응답 생성 | 문서 검색·문맥 구성 |
| 한계 | 과도한 권한·취소 실패 | 유해·민감 응답 생성 | 문서 인젝션·권한 누락 |

> 요약: 챗봇은 응답, RAG는 검색, 에이전트는 행동을 통제한다

### 쉽게 이해하기 (학습용)

- 챗봇은 말, RAG는 검색, 에이전트는 실제 행동 위험 관리

## Ⅵ. 실무 사례

1. 메일 에이전트의 **발송 대상·내용 사용자 승인**

### 쉽게 이해하기 (학습용)

- 메일 에이전트는 초안 작성까지만 자동 수행하고 외부 발송 전 수신자·본문·첨부파일을 사용자에게 보여 준 뒤 명시적으로 승인받는다.

## Ⅶ. 결론

- AI 판단 오류가 실제 시스템 피해로 이어지는 것을 막기 위해 도구 권한·행동 가역성·사용자 승인·실행 증거를 검토하여, 에이전트의 호출별 최소 권한과 통제된 실행을 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 오류 발생 시 제한 범위 내 정지·설명·복구 가능한 시스템
