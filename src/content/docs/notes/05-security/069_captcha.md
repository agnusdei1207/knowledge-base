## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAPTCHA(Completely Automated Public Turing test to tell Computers and Humans Apart)**: 컴퓨터와 인간을 판별하기 위해 시스템이 자동으로 문제를 출제하고 응답을 평가하는 역 튜링 테스트 기반의 보조 접근 통제 기술.
- **자동화 공격에 의한 자원 고갈 및 사기(Automated Bot Attack Defect)**: 공격자가 대규모 봇넷과 헤드리스 브라우저를 이용하여 초당 수천 건의 무차별 대입(Credential Stuffing), 계정 대량 생성, 티켓팅 매크로, 스크래핑을 실행하여 시스템 가용성과 비즈니스 무결성을 파괴하는 위협.

</details>

- 정의/개념: 인간 사용자의 고유한 행위 패턴(마우스 궤적, 클릭 타이밍)과 브라우저 핑거프린팅을 분석하여 **위험 점수(Risk Score) 산출 $\rightarrow$ 적응형 챌린지(Adaptive Challenge) 부과 $\rightarrow$ 서명된 일회용 검증 토큰 발급 $\rightarrow$ 백엔드 1:1 목적 결속(Purpose Binding) 검증** 을 집행하는 **봇 탐지 및 완화(Bot Mitigation) 아키텍처**
- 배경/필요성: IP 차단은 프록시를 갈아 끼우는 비용만 치르면 무력화되고 정적 퍼즐은 AI 솔버가 사람보다 싸게 푸는 순간 기능을 잃으므로, 통과 여부를 사람·봇의 이분 판정 대신 행동 신호로 산출한 위험 점수에 맡기고 의심 구간에만 마찰을 부과하는 판정 계층을 인증 앞단에 둘 요구

#### 한줄 요약
- CAPTCHA는 봇을 완전히 가려내는 장치가 아니라 자동화 공격 1건당 비용을 사람 손을 빌려야 할 만큼 끌어올려 수지가 맞지 않게 만드는 장치다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **reCAPTCHA v2 vs reCAPTCHA v3**:
  - **v2 (Interactive Challenge)**: 사용자에게 명시적인 체크박스 클릭 또는 이미지 타일 선택 퍼즐을 요구하는 인터랙티브 방식.
  - **v3 (Invisible Risk Score)**: 사용자 인터랙션 없이 백그라운드에서 사용자 행동을 관찰하여 `0.0`(확실한 봇)부터 `1.0`(정상 인간)까지의 점수를 반환하는 무마찰 방식.
- **목적 결속(Purpose Binding)**: 발급된 CAPTCHA 검증 토큰을 특정 로그인 폼이나 결제 요청 API와 1:1로 암호학적으로 결속시켜, 타 API 엔드포인트로의 토큰 재사용을 방지하는 원칙.

</details>

- **적응형 위험 기반 챌린지 (Adaptive Friction)**: 저위험 세션은 무마찰(v3)로 즉시 통과시키고, 고위험 의심 세션에만 퍼즐(v2)이나 MFA를 동적 부과
- **백엔드 암호학적 토큰 검증**: 클라이언트의 챌린지 통과 신호를 그대로 믿지 않고, 백엔드 서버가 CAPTCHA 검증 API를 호출하여 서명, 만료일, 중복 사용 여부를 전수 검증
- **접근성(WCAG 2.2) 호환 대체 경로**: 시각 및 지체 장애인을 위한 오디오 챌린지 및 대안적 다중 인증(MFA) 제공

#### 한줄 요약
- 마찰을 줄일수록 정상 사용자 이탈은 줄지만 임계값을 낮춘 만큼 봇 통과분도 함께 늘어나므로, 점수 임계치 설정이 곧 전환율과 보안을 가르는 지점이 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **CAPTCHA 4대 핵심 컴포넌트**:
  1. **Client Telemetry Collector**: 브라우저 핑거프린트, 마우스 이동 궤적, 터치 이벤트 수집.
  2. **Risk Engine (위험 평가 엔진)**: ML 알고리즘으로 수집 데이터를 평가하여 봇 확률 점수 산출.
  3. **Challenge Generator**: 이미지 분류, 텍스트 왜곡, 오디오 등 적응형 과제 생성.
  4. **Backend Verifier**: 검증 토큰의 1회성, 만료시간, 세션 바인딩을 최종 심사.

</details>

```text
[ 클라이언트 (웹 브라우저 / 모바일 앱) ]
                 │ (1. 마우스 궤적, 환경 텔레메트리 전송)
                 ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. CAPTCHA 클라우드 서비스 (Risk Engine & Challenge Provider) ]        │
│  ├─ 머신러닝 위험 점수 계산 (Score: 0.0 ~ 1.0)                          │
│  ├─ 저위험(Score > 0.7) ➔ 무마찰 통과 & 서명된 검증 토큰 즉각 발급       │
│  └─ 고위험(Score <= 0.7) ➔ [ 이미지 퍼즐 챌린지 제시 ➔ 정답 시 토큰 발급 ]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (2. 서명된 일회용 검증 토큰 반환)
                                     ▼
[ 클라이언트 ➔ 비즈니스 요청 + CAPTCHA 토큰 첨부 전송 ]
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 애플리케이션 백엔드 검증 계층 (Backend Verification Layer) ]       │
│  ├─ CAPTCHA 서버로 시크릿 키와 토큰 전송하여 2차 진위 확인             │
│  ├─ 토큰 재사용(Replay) 검증: 1회 소비 후 토큰 ID 캐싱/폐기             │
│  ├─ 목적 결속(Purpose Binding) 확인: 요청 액션(`login`)과 토큰 액션 대조│
│  └─ [ 전 항목 통과 ➔ 정상 비즈니스 트랜잭션 실행 승인 ]                 │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 클라이언트 텔레메트리가 위험 엔진에서 평가되어 서명 토큰이 발급되고, 백엔드가 CAPTCHA 서버와의 2차 검증을 거쳐 최종 인가하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **텔레메트리 수집기** | 브라우저 헤더, 핑거프린트, 마우스 가속도, 터치 좌표 등 인간 행동 신호 수집 | Data Ingestion |
| **위험 평가 엔진 (ML)** | 수집 신호와 IP 평판을 머신러닝 모델로 분석하여 봇 위험 점수(0.0~1.0) 도출 | Analysis Core |
| **적응형 챌린지 생성기** | 의심 트래픽에 대해 시각/청각 퍼즐을 동적으로 제시하여 튜링 테스트 집행 | Challenge Spec |
| **백엔드 토큰 검증기** | 애플리케이션 서버에서 검증 토큰의 서명, 만료일(`exp`), 세션 일치성 확인 | Anti-Bypass |
| **Rate Limiter (호출률 제어)**| CAPTCHA 전단에서 동일 IP/단말의 과도한 요청을 사전 차단하여 봇 비용 증대 | Rate Limiting |

#### 한줄 요약
- 판정은 외부 CAPTCHA 서비스가 내리지만 그 결과를 받아들일지는 백엔드 토큰 검증이 정하므로, 클라이언트 신호만 믿는 구현은 통제 계층 하나를 통째로 비워 둔 것과 같다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **reCAPTCHA v3 + v2 적응형 5단계 하이브리드 흐름**:
  1. 클라이언트 행동 신호 수집 및 v3 위험 점수 산출
  2. 고위험 판정 시 v2 인터랙티브 퍼즐 트리거
  3. 퍼즐 해결 성공 시 서명된 일회용 토큰 발급
  4. 백엔드 서버가 CAPTCHA 검증 API 호출
  5. 토큰 무결성 및 Replay 검증 통과 시 로그인 승인

</details>

```text
1. [행동 신호 수집] 사용자가 로그인 화면 진입 ➔ 스크립트가 마우스 이동 궤적 및 환경 핑거프린트 수집
            │
            ▼
2. [무마찰 위험 평가 (v3)] 위험 엔진이 실시간 분석하여 봇 위험 점수 산정
            │
            ├─ [Score >= 0.7 (인간 판정)] ➔ 사용자 개입 없이 검증 토큰 자동 발급 후 4단계 이동
            ▼
3. [적응형 챌린지 부과 (v2)] Score < 0.7 (봇 의심) ➔ 화면에 "신호등이 포함된 이미지 선택" 챌린지 팝업
            │
            ▼
4. [정답 제출 및 토큰 발급] 퍼즐 해결 완료 ➔ CAPTCHA 서버가 암호학적으로 서명된 단기 일회용 토큰 발급
            │
            ▼
5. [백엔드 목적 결속 및 재전송 검증]
    ├─ 애플리케이션 백엔드가 시크릿 키로 CAPTCHA 검증 API 호출 (`verify`)
    ├─ 토큰 재사용(Replay) 여부 및 액션 일치(`action == 'login'`) 확인
    └─ [검증 통과 ➔ 정상 로그인 트랜잭션 처리 완료]
```

**동작 원리**

1. **공격 비용의 극대화(Cost Inflation)**: 봇 공격자에게 컴퓨팅 연산 및 인간 작업(CAPTCHA Farm) 비용 강제
2. **무마찰 사용자 경험**: 대다수 정상 사용자에게는 퍼즐을 띄우지 않고 백그라운드에서 투명하게 판별
3. **위조 토큰 유입 원천 봉쇄**: 백엔드에서 전용 Secret Key를 사용하여 CAPTCHA 서버와 2차 교차 검증
4. **리플레이 재사용 방어**: 사용 완료된 토큰 ID를 메모리/Redis에 캐싱하여 동일 토큰 재전송 즉각 거부
5. **다계층 방어 연계**: CAPTCHA 단독에 의존하지 않고 WAF 봇 시그니처 및 Rate Limiting과 병행

#### 한줄 요약
- 저위험 경로는 사용자 개입 없이 지나가지만 두 갈래 모두 백엔드 토큰 검증으로 합류하므로, 마찰의 유무와 무관하게 신뢰의 최종 근거는 서버가 1회 소비한 토큰 하나로 수렴한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CAPTCHA 3대 세대별 기술 비교**: 문제 풀이형(v2), 위험 점수형(v3), 지능형 적응 혼합 모델의 비교.

</details>

| 비교 항목 | 인터랙티브 문제 풀이형 (v2) | 무마찰 위험 점수형 (v3) | 지능형 적응 혼합 모델 (v3 + v2) |
|:---|:---|:---|:---|
| **사용자 경험 (UX)** | **마찰 발생 (퍼즐 풀이 시간 소요)** | **완전 무마찰 (백그라운드 자동 통과)** | **위험 시에만 선별적 마찰 발생 (최적)** |
| **통제 방식** | 정적 체크박스 및 이미지 타일 선택 | 머신러닝 행동 핑거프린트 점수화 | **v3 점수 평가 후 임계치 미달 시 v2 호출**|
| **AI/OCR 솔버 방어** | **취약 (딥러닝 비전 모델로 풀이 가능)**| **우수 (행동 궤적 복제 난이도 극상)** | **최상 (행동 분석 + 동적 챌린지 결합)** |
| **백엔드 튜닝 필요성**| 낮음 (Pass/Fail 단순 판정) | **높음 (비즈니스별 점수 임계치 설정)**| 보통 (단계별 자동 에스컬레이션 정책) |

#### 한줄 요약
- 세 세대의 차이는 봇 판별력이 아니라 마찰 비용을 누구에게 얼마나 물릴 것인가에 있으며, 혼합 모델은 그 비용을 의심 구간에만 몰아준 결과다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OWASP OAT-009 (CAPTCHA Bypass)**: OCR 인식, 딥러닝 AI 솔버, 매크로 대행을 통해 CAPTCHA 통제를 무력화하는 자동화 공격 패턴.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 딥러닝 AI 비전 모델 및 OCR 자동화 도구를 통해 **단순 이미지 퍼즐 CAPTCHA가 우회되는 공격 발생(OAT-009)** | **마우스 이동 궤적, 키 타이밍 등 행동 바이오메트릭스 복합 분석 엔진 도입 및 적응형 점수 모델 적용** | AI 봇의 자동 풀이 무력화 및 공격자의 자동화 수행 비용 극대화 |
| 시각/지체 장애인이 이미지 퍼즐을 풀지 못하여 **웹 서비스 이용이 차단되는 웹 접근성 법적 컴플라이언스 위반** | **W3C WCAG 2.2 표준 준수, 음성 오디오 챌린지 및 이메일/SMS 다중 인증(MFA) 대체 경로 제공** | 디지털 취약계층 접근성 100% 보장 및 법적 컴플라이언스 충족 |
| 공격자가 단 1회 획득한 정상 검증 토큰을 가로채어 **대량의 위조 요청에 반복 재사용하는 Replay 공격** | **백엔드에서 토큰 1회 소비 후 즉시 폐기(Anti-replay 캐싱) 및 원래 의도된 API 액션과의 1:1 목적 결속 강제** | 토큰 가로채기 및 대량 복제 재전송 공격 100% 원천 차단 |

#### 한줄 요약
- 봇을 걸러내려 마찰을 높일수록 장애인 사용자가 먼저 걸러지므로, 대체 인증 경로를 갖추지 못한 강화는 보안 이득을 접근성 위반으로 되갚는다.

## Ⅶ. 결론

- 봇 위험 점수에 따라 **적응형 CAPTCHA**를 적용하고 토큰·호출률을 함께 검증

#### 한줄 요약
- CAPTCHA 단독으로는 사람을 고용한 우회까지 막을 수 없으므로, 호출률 제어·WAF와 함께 공격 단가를 올리는 여러 층 가운데 하나로 배치해야 한다.
