## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CAPTCHA (컴퓨터·사람 구별 역 튜링 테스트)**: 사람 사용자와 자동화 스크립트(Bot)를 역 튜링 테스트 방식으로 판별하는 보조 접근 통제 기술
- **reCAPTCHA**: 구글의 대표적 봇 탐지 서비스로 텍스트/이미지 문제 풀이(v2) 및 무마찰 위험 점수 평가(v3) 알고리즘을 결합한 솔루션
- **봇 (Bot)**: 대량 가입, Credential Stuffing, 웹 스크래핑 등을 목적으로 자동화된 악성 작업을 대량 수행하는 프로그램

</details>

- 정의: 인간과 자동화된 매크로 봇을 판별하여 비정상적 트래픽 진입을 차단하는 역 튜링 테스트 기반 보조 접근 통제 체계
- 배경: 웹 서비스 공개 접점을 대상으로 한 대량 계정 생성, 크리덴셜 스터핑, 티켓팅 매크로 공격 차단 필요성 증대

#### 한줄 요약

- 매크로 봇의 대량 자동화 공격 경제성을 무력화하고 정상 사용자를 판별하여 서비스 진입을 통제하는 방어 체계 구축

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **검증 토큰 (Verification Token)**: CAPTCHA 서버가 챌린지 성공 시 발급하는 단기 일회용 암호 증표로 백엔드 검증에 활용되는 데이터
- **목적 결속 (Purpose Binding)**: 발급된 검증 토큰을 특정 세션 및 원래 요청된 API 동작에만 1:1로 결합하여 타 요청 재사용을 막는 보안 원칙
- **호출률 제한 (Rate Limiting)**: 동일 IP 또는 사용자 단위로 일정 시간 내 요청 횟수를 제어하여 봇 공격을 차단하는 기본 네트워크 통제 기법
- **MFA (다중 요소 인증)**: 고위험 봇 시도 판명 시 추가적인 OTP/SMS 생체 인증으로 전환하는 다중 인증 체계

</details>

- **동적 위험 기반 챌린지**: 사용자 행위 특성 및 단말 신호를 분석하여 산출된 위험 점수에 따라 필요한 시점에만 동적 챌린지 부과
- **백엔드 목적 결속 검증**: 애플리케이션 백엔드에서 검증 토큰의 서명 무결성, 1:1 목적 결속, 만료 시간 및 일회성 엄격 확인
- **다층 방어 연동**: 단순 CAPTCHA 단독 운용을 지양하고 WAF 봇 룰, 호출률 제한(Rate Limiting), MFA 체계와 상호 연계

#### 한줄 요약

- 검증 토큰의 1:1 목적 결속 및 백엔드 일회성 검증을 집행하고 Rate Limiting 및 MFA와 연동하여 봇 방어력 극대화

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **위험 엔진 (Risk Engine)**: IP 평판, 브라우저 핑거프린트, 마우스 이동 궤적, 요청 주기를 실시간 분석하여 자동화 위험 점수를 산출하는 분석 모듈
- **도전 문제 (Challenge Issue)**: 고위험 판단 시 사용자에게 제시하는 이미지 분류, 퍼즐 맞추기, 오디오 인터랙션 등의 과제

</details>

```text
                         [위험 엔진]
                        /          \
                 [요청 신호 수집]  [도전 문제]
                                       │
                                  [검증 토큰]
                                       │
                         [애플리케이션 백엔드 검증]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **요청 신호 수집** | Client IP, HTTP 헤더, 브라우저 핑거프린팅, 마우스/터치 행동 이벤트 수집 | Data Ingestion |
| **위험 엔진 (Risk Engine)** | 수집 신호를 ML 알고리즘으로 평가하여 봇 위험 점수(0.0~1.0) 실시간 산출 | Analysis Core |
| **도전 문제 (Challenge)** | 고위험 세션에 대해 이미지 퍼즐/오디오 등 명시적 과제를 동적 제시 | Interactive Task |
| **검증 토큰 (Token)** | 클라이언트의 도전 문제 통과 시 서버가 서명하여 발급하는 단기 일회용 증표 | Signed Token |
| **애플리케이션 백엔드** | 토큰 무결성, 일회성(Anti-replay), 목적 결속 확인 후 인가 또는 차단 집행 | Policy Decision |

#### 한줄 요약

- 위험 엔진이 봇 위험도를 평가하여 과제를 발급하고, 백엔드가 서명 토큰의 무결성을 최종 검증하는 3자 구조 확립

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **적응형 통제 (Adaptive Control)**: 산출된 위험 점수에 따라 무마찰 통과, 챌린지 부여, MFA 요구, IP 즉시 차단을 동적으로 분기하는 통제 기법
- **재전송 검증 (Anti-replay Check)**: 한번 사용된 검증 토큰의 재사용 시도를 백엔드 캐시/DB 대조를 통해 원천 차단하는 검증 절차

</details>

```text
[사용자 요청]
      │
      ▼
1. 계정 / 기기 / 행위 맥락 수집
      │
      ▼
2. 자동화 위험 점수 산정
      │
      ├── 저위험 ─────────────► [업무 요청 즉시 허용]
      │
      └── 중·고위험
              │
              ▼
      3. 적응형 도전 문제 생성
              │
              ▼
      [도전 문제 응답 제출]
              │
              ▼
      4. 응답 유효성 판정 및 토큰 발급
              │
              ▼
      5. 백엔드 목적 결속 및 재전송 검증
              │
              ▼
      [업무 요청 최종 인가]
```

### 동작 원리

1. 맥락 수집: 단말 브라우저 환경, IP 평판, 마우스 궤적 등 행동 텔레메트리 수집
2. 위험도 평가: 머신러닝 위험 엔진이 수집 데이터를 분석하여 봇 확률 점수 산출
3. 적응형 과제 부과: 위험 점수에 상응하는 텍스트/이미지/오디오 챌린지 동적 제공
4. 정답 판정 및 토큰 발급: 사용자의 챌린지 응답을 검증하고 서명된 일회용 검증 토큰 반환
5. 백엔드 무결성 검증: 애플리케이션 서버가 토큰의 유효시간, 중복 사용 여부, 세션 결속 상태를 확인 후 최종 인가

#### 한줄 요약

- 텔레메트리 수집, 위험 점수 산정, 적응형 챌린지 부여, 정답 판정 및 백엔드 토큰 재전송 방지 검증 수행

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **문제형 CAPTCHA (reCAPTCHA v2)**: 이미지 선택, 퍼즐 맞추기 등 사용자에게 직접적 과제 해결을 요구하는 명시적 인터랙션 방식
- **점수형 CAPTCHA (reCAPTCHA v3)**: 사용자 개입 없이 백그라운드 행위 분석만으로 0.0~1.0 점수를 반환하는 무마찰(Invisible) 방식
- **적응형 CAPTCHA (Adaptive CAPTCHA)**: 평소 무마찰 점수형으로 감시하다가 이상 징후 감지 시에만 문제형 챌린지를 동적 제시하는 혼합 방식
- **오탐 (False Positive)**: 정상 사용자를 악성 봇으로 오인하여 불필요한 과제를 부과하거나 서비스를 차단하는 오류

</details>

| CAPTCHA 유형 | **문제 풀이형 (v2)** | **위험 점수형 (v3)** | **적응형 혼합 모델** |
|:---|:---|:---|:---|
| 사용자 경험 (UX) | 퍼즐 풀이로 인한 마찰 발생 | 완전 무마찰 백그라운드 동작 | 위험 시에만 선별적 마찰 발생 |
| 통제 메커니즘 | **문제형 CAPTCHA** 기반 명시적 입력 확인 | **점수형 CAPTCHA** 기반 ML 행동 분석 점수 산출 | **적응형 CAPTCHA** 기반 단계별 위험 대응 |
| 장단점 및 한계 | 확실한 봇 차단 반면 **사용자 피로도 및 이탈률 증가** | 우수한 UX 반면 **오탐 위험 및 백엔드 임계치 튜닝 부담** | 최적의 균형 제공 반면 **정책 설계 복잡도 증가** |

#### 한줄 요약

- UX 저해 문제를 해결하기 위해 단순 문제 풀이형에서 무마찰 점수형 및 지능형 적응 혼합 모델로 전환

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OWASP OAT-009 (CAPTCHA Bypass)**: OCR 인식, 딥러닝 AI 솔버, 매크로 대행을 통해 CAPTCHA 통제를 무력화하는 자동화 공격 패턴
- **W3C WCAG 2.2**: 시각 및 청각 장애인이 웹 서비스 이용 시 CAPTCHA 장벽에 막히지 않도록 대체 인증을 요구하는 웹 접근성 표준
- **대체 경로 (Alternative Path)**: 장애인을 위해 오디오 챌린지, 이메일/SMS 2차 인증 등 대체 검증 수단을 제공하는 통제 설계

</details>

| 장애 및 위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| AI 기반 OCR 풀이 및 솔버를 통한 통제 우회 | 단순 이미지 변형 챌린지의 AI 비전 모델 학습 무력화 (**OWASP OAT-009**) | 행동 바이오메트릭스 복합 분석 및 인간 마우스 궤적 기반 판별 강화 | 딥러닝 봇의 자동 풀이 무력화 및 공격 비용 극대화 |
| 시각/지체 장애인의 서비스 접근 차단 이슈 | 시각 중심 이미지 퍼즐 강제로 인한 웹 접근성 지침 미준수 | **W3C WCAG 2.2** 준수 및 오디오/SMS 기반 **대체 경로(Alternative Path)** 제공 | 디지털 취약계층 접근성 보장 및 법적 컴플라이언스 준수 |
| 토큰 탈취 및 대량 재전송(Replay) 공격 | 백엔드 검증 로직 부실로 동일 토큰을 여러 요청에 재사용 | 검증 토큰 1:1 **목적 결속**, **호출률 제한**, IP 평판 복합 검증 | 토큰 복제 및 분산 대량 재사용 공격 원천 차단 |

#### 한줄 요약

- AI OCR 우회 방지를 위한 행동 분석 결합, WCAG 2.2 대체 경로 제공, 백엔드 목적 결속 및 Replay 방지 구현

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **공격 경제성 저하 (Attacker Cost Inflation)**: CAPTCHA를 단독 방어벽이 아닌 봇 공격자의 컴퓨팅 자원 및 시도 비용을 극대화하여 공격을 자진 포기하게 만드는 보안 전략

</details>

- 자동화 매크로 공격에 대응하여 **공격 경제성 저하** 활용 달성하기 위해, 저위험 구간은 **호출률 제한(Rate Limiting)**, 중위험은 **적응형 CAPTCHA**, 고위험 핵심 자산은 **MFA** 활용 계층 배치하는 다층 보안 체계 구축 필수

#### 한줄 요약

- 저위험 구간 호출률 제한, 중위험 구간 적응형 CAPTCHA, 고위험 자산 MFA 연계를 통한 계층적 봇 방어 체계 확립
