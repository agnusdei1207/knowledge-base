## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **MITRE ATT&CK**: 공격자의 전술·기법을 행렬로 체계화한 지식베이스.
- **탐지 커버리지(Detection Coverage)**: ATT&CK 기법 중 탐지 가능한 범위를 나타내는 보안 지표.

</details>

- 정의/개념: 공격자 **TTP** 분류로 탐지·대응을 검증하는 지식베이스
- 배경/필요성: IOC 변경으로 시그니처 탐지가 우회되어 **탐지 공백** 측정 불가

#### 한줄 요약
- 공격자 행동(TTP) 매트릭스를 기반으로 보안 탐지 룰을 개발하고 적대적 모의실행으로 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Tactics vs Techniques**: 공격자가 달성하려는 전술적 목표(Why)와 이를 실행하는 구체적인 기술 수단(How).
- **Adversary Emulation (적대적 모의실행)**: 실제 공격자 그룹(APT)의 TTP 스크립트를 방어 시스템에서 직접 실행하여 탐지 및 차단 동작을 실증하는 검증.

</details>

- 도구 변경에도 유지되는 **TTP** 중심 공격 행위 표준화
- ATT&CK Navigator의 **탐지 커버리지** 기반 투자 우선순위 가시화
- **적대적 모의실행** 기반 SIEM·EDR 탐지 규칙의 실효성 검증

#### 한줄 요약
- TTP 중심 표준화, 정량적 갭 분석 시각화, 적대적 모의실행(Atomic Red Team) 실증을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Data Sources (데이터 소스)**: 특정 공격 기법(T-ID)을 탐지하기 위해 반드시 수집해야 하는 엔드포인트/네트워크 원시 이벤트 로그.

</details>

```text
[ATT&CK 지식베이스]
|
+-- [도메인]
|   `-- [전술]
|       `-- [기법]
|           `-- [서브기법]
|
+-- [데이터 소스]
`-- [완화책]
```

선의 의미: 가지는 분류 계층과 지식베이스의 포함 관계

| 구성요소 | 책임 |
|:---|:---|
| **도메인** | Enterprise·Mobile·ICS 매트릭스 구분 |
| **전술** | 공격자가 달성하려는 목적 분류 |
| **기법·서브기법** | 전술을 수행하는 행위와 구현 방식 식별 |
| **데이터 소스** | 기법 탐지에 필요한 원시 이벤트 지정 |
| **완화책** | 공격 기법의 실행 가능성 제한 |

#### 한줄 요약
- 전술(Why), 기법(How), 서브기법, 데이터 소스(로그), 시스템 완화책이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Atomic Red Team**: 수백 개의 MITRE ATT&CK 기법을 1:1로 테스트할 수 있도록 설계된 오픈소스 독립 모의 공격 프레임워크.

</details>

```text
[위협 정보]
     |
     v
1. T-ID 우선순위화
     |
     v
2. 데이터 소스 수집
     |
     v
3. 탐지 규칙 개발
     |
     v
4. 적대적 모의실행
     |
     +-- 경보 미발생 -- 데이터·규칙 보완 --+
     |                                      |
     +------------- 재검증 <---------------+
     |
     `-- 경보 발생 --> [커버리지 등록]
```

**동작 원리**

1. **T-ID 우선순위화**: 표적 공격 그룹의 핵심 기법 선정
2. **데이터 소스 수집**: T-ID별 필수 이벤트 확보
3. **탐지 규칙 개발**: SIEM·EDR 행위 상관 규칙 구현
4. **적대적 모의실행**: 공격 스크립트로 경보 발생 검증

#### 한줄 요약
- 위협 T-ID 선정 → 데이터 소스 수집 → 탐지 규칙 구현 → Atomic 모의실행 검증 → 커버리지 매트릭스 등록 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Enterprise Matrix** vs **Mobile Matrix** vs **ICS Matrix**.

</details>

| 도메인 영역 | Enterprise Matrix (기업 IT/Cloud) | Mobile Matrix (스마트폰) | ICS Matrix (산업제어시스템) |
|:---|:---|:---|:---|
| 적용 대상 | 기업 IT·클라우드 | Android·iOS | 산업제어시스템 |
| 핵심 위협 | **권한 상승**·횡적 이동 | **기기 접근**·네트워크 도청 | **제어 명령 조작**·SIS 무력화 |
| 탐지 데이터 | **EDR**·인증·API 로그 | **MDM**·앱 권한 로그 | **산업 프로토콜** 패킷 |
| 한계 | 플랫폼 범위가 넓어 선별 필요 | 기기별 관측 권한 제약 | 가용성 제약으로 모의실행 제한 |

#### 한줄 요약
- Enterprise는 기업 IT/클라우드, Mobile은 스마트폰 OS, ICS는 제조/발전 산업제어망에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Observation Bias (관찰 편향)**: 단순 룰(whoami 등)만 대량 등록하여 매트릭스를 인위적으로 채우고 실제 고위험 TTP 탐지 검증을 누락하는 보안 운영 오류.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 룰 배포 후에도 실제 공격 경보 미발생 | **적대적 모의실행** 상시 검증 | 탐지 규칙의 실효성과 공백 확인 |
| 매트릭스 채우기식 저위험 룰 양산 | **CTI** 기반 TTP 우선순위화 | 핵심 공격 경로에 검증 자원 집중 |
| 도구별 공격 명칭 파편화로 협업 지연 | 인시던트에 **T-ID** 태깅 | 분석·대응 용어의 일관성 확보 |
| 정상 관리 도구 행위의 오탐 증가 | 부모·자식 프로세스 **상관분석** | 정상 업무와 공격 행위 구분 |

#### 한줄 요약
- 모의실행으로 룰 실효성을 검증하고, CTI로 TTP 우선순위를 정하며, T-ID 표준화로 대응 속도를 극대화한다.

## Ⅶ. 결론

- 위협 TTP와 관측 가능성에 따라 **T-ID** 선별 후 모의실행 검증

#### 한줄 요약
- MITRE ATT&CK은 전술(Why)과 기법(How)의 매트릭스 분류 및 모의실행 검증을 통해 TTP 기반 능동 보안 커버리지를 완성하는 핵심 지식베이스다.
