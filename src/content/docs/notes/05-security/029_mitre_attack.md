## 미리 알고가기

- **MITRE ATT&CK(Adversarial Tactics, Techniques, and Common Knowledge)**: 실제 관찰된 공격 행동을 전술·기법·절차와 대응 정보로 분류한 지식체계
- **전술(Tactic)**: 공격자가 특정 시점에 달성하려는 목적
- **기법(Technique)**: 전술의 목적을 달성하기 위해 사용하는 공격 행위
- **서브기법(Sub-Technique)**: 하나의 기법을 더 구체적인 수법으로 나눈 단위
- **절차 사례(Procedure Example)**: 특정 공격 그룹·도구·캠페인이 기법을 실제 사용한 관찰 사례
- **완화(Mitigation)**: 공격 행위의 성공 가능성이나 피해를 줄이는 예방 통제
- **탐지 전략(Detection Strategy)**: 특정 공격 행동을 어떤 관점과 데이터로 찾을지 정한 방어 접근
- **분석 규칙(Analytics)**: 로그 조건·상관관계·통계로 공격 행동을 판별하는 구현 논리
- **기업 도메인(Enterprise Domain)**: 기업 단말·서버·신원·클라우드 환경의 공격 행동을 분류한 지식 영역
- **모바일 도메인(Mobile Domain)**: 모바일 기기와 응용의 공격 행동을 분류한 지식 영역
- **산업제어시스템 도메인(Industrial Control Systems Domain, ICS Domain)**: 산업 공정과 제어 설비의 공격 행동을 분류한 지식 영역
- **정보기술(Information Technology, IT)**: 정보의 생성·처리·저장과 업무 서비스를 지원하는 기술 환경
- **운영기술(Operational Technology, OT)**: 물리 공정과 설비를 감시·제어하는 기술 환경
- **위협 헌팅(Threat Hunting)**: 기존 경보를 기다리지 않고 가설을 세워 숨은 침해 증거를 능동적으로 찾는 활동
- **커버리지(Coverage)**: 선정한 공격 행동 중 실제 데이터·탐지·대응으로 검증한 범위

## Ⅰ. 개요

- 정의/개념: 실제 관찰 기반의 **공격 전술·기법·절차 지식 체계**
- **배경/필요성**: IoC·제품 목록만으로는 **행동 기반 탐지 커버리지 검증 곤란**

### 쉽게 이해하기 (학습용)

- ATT&CK은 공격자가 실제로 사용한 수법을 같은 언어로 정리해 위협 분석가와 탐지 개발자 및 대응팀이 연결해서 일하게 한다.

## Ⅱ. 특징

- **전술→기법→서브기법**으로 공격 목적과 행동을 계층화한다.
- **절차 사례·완화·탐지 전략**을 기법별로 연결한다.
- **Enterprise·Mobile·ICS 행렬**은 환경별 범위를 구분하나 관찰 편향이 있다.

### 쉽게 이해하기 (학습용)

- 기법 번호 옆에 보안 제품 이름만 적어서는 실제로 잡는지 알 수 없고 필요한 로그와 판별 조건 및 대응 결과까지 확인해야 한다.

## Ⅲ. 구성요소 및 구조

```mermaid
flowchart TD
    A[도메인·행렬] --> B[전술]
    B --> C[기법·서브기법]
    C --> D[절차 사례]
    C --> E[완화·탐지 전략]
    D --> F[분석·검증 결과]
    E --> F
```

| 설계 요소 | 설명 |
|:---|:---|
| 도메인·행렬 | **환경별 공격 목적·기법 배치** |
| 전술 | **공격자가 달성하려는 목적** |
| 기법·서브기법 | **목적을 이루는 공격 행동** |
| 절차 사례 | **그룹·도구의 실제 사용 근거** |
| 완화·탐지 전략 | **예방·관측 접근 연결** |
| 분석·검증 결과 | **로그 규칙·모의공격 증적** |

> 요약: 공격 행동과 탐지·검증 증적을 연결

### 쉽게 이해하기 (학습용)

- 환경과 공격 목적에서 세부 행동을 고르고 실제 사례를 근거로 필요한 통제·로그·탐지 규칙과 시험 결과를 연결한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant T as 위협 분석팀
    participant A as ATT&CK 지식 체계
    participant D as 탐지 개발팀
    participant S as 보안 데이터
    participant V as 모의공격·헌팅
    T->>A: 위협 행동 조회
    A-->>D: 기법·절차 근거 전달
    D->>S: 수집·분석 규칙 적용
    S-->>V: 탐지 결과 전달
    V-->>D: 검증 공백 반환
    D->>A: 구현·증적 매핑
```

| 절차 | 설명 |
|:---|:---|
| 위협 행동 조회 | 자산·시나리오에 맞는 기법 선택 |
| 기법·절차 근거 전달 | 실제 사용 사례와 변형 확인 |
| 수집·분석 규칙 적용 | 필요한 로그와 상관조건 구현 |
| 탐지 결과 전달 | 경보·시간선·대응 근거 제공 |
| 검증 공백 반환 | 모의행위로 미탐·지연 식별 |
| 구현·증적 매핑 | 검증 결과를 기법에 기록 |

> 요약: 공격 기법을 실제 로그와 시험 결과에 연결한다.

### 쉽게 이해하기 (학습용)

- 관심 기법을 고른 뒤 그 행동이 남기는 로그로 규칙을 만들고 공격을 재현해 실제로 잡히는지 확인해야 커버리지로 인정할 수 있다.

## Ⅴ. 종류 및 비교

| ATT&CK 도메인 | 공통 | Enterprise | Mobile | ICS |
|:---|:---|:---|:---|:---|
| 적용 기준 | 위협·탐지 공통 언어 | 단말·서버·신원 방어 | 모바일 권한·센서 방어 | OT 가시성·안전 방어 |
| 핵심 특징 | 전술·기법·절차 분류 | 기업 IT·클라우드 행동 | 모바일 기기·앱 행동 | 공정·제어 설비 행동 |
| 한계 | 목록 채우기식 운영 | 플랫폼별 로그 공백 | 기기 파편화·관측 제한 | 가용성·안전 영향 |

> 요약: 환경별 행동·증거·영향에 맞는 도메인 선택

### 쉽게 이해하기 (학습용)

- 기업 단말과 스마트폰과 공장 제어기는 공격 행동과 남는 증거 및 실패 영향이 다르므로 맞는 도메인을 선택해야 한다.

## Ⅵ. 실무 사례

1. 모의공격으로 **기법별 탐지·대응 증적 검증**

### 쉽게 이해하기 (학습용)

- 규칙 존재만 확인하지 않고 모의공격으로 경보·조사·차단까지 실제 작동하는지 검증한다.

## Ⅶ. 결론

- 공격자 행동 중심으로 탐지 공백을 찾기 위해 자사 위협·관련 기법·데이터 소스·분석 규칙·검증 증거를 검토하여, ATT&CK 기반 탐지 커버리지를 증적 중심으로 관리해야 한다.

### 쉽게 이해하기 (학습용)

- ATT&CK의 가치는 행렬을 많이 채우는 데 있지 않고 중요한 공격 행동을 실제 데이터에서 찾아 대응할 수 있음을 시험으로 증명하는 데 있다.
