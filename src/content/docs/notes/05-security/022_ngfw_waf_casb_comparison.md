## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **NGFW (차세대 방화벽)**: 포트 번호 속이고 들어오는 놈들을 잡아내기 위해, 데이터 패킷(패킷)를 다 뜯어보고 실제 앱이 뭔지 가려내는 통합 네트워크 문지기다.
- **WAF (웹 방화벽)**: 오직 웹(HTTP/HTTPS) 공격(악성 스크립트, SQL 삽입 등)만 전문적으로 잡아내는 웹 전용 정밀 탐지기다.
- **CASB (클라우드 접근 중개)**: 직원들이 회사 몰래 클라우드(SaaS)에 민감한 문서를 올리는지 감시하고 통제하는 클라우드 경찰관이다.

</details>

- 정의: 네트워크 경계(NGFW), 웹 서버 앞단(WAF), 클라우드 접속 구간(CASB)에서 각자의 특화된 문맥을 나누어 철통 통제하는 보안 솔루션 트리오다.
- 배경: 옛날 방화벽 하나만 믿고 있다가, 정교한 웹 게시판 해킹이나 직원들이 몰래 쓰는 클라우드(섀도 IT)로 데이터가 줄줄 샜기 때문이다.

#### 한줄 요약

- 네트워크 전체는 NGFW가 막고, 웹 해킹은 WAF가 저격하며, 직원들의 클라우드 뻘짓은 CASB가 감시한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **App-ID**: 단순히 포트 번호(80, 443)만 보고 패스해 주는 게 아니라, 안에 들어있는 진짜 데이터가 유튜브인지 토렌트인지 내용물을 식별하는 기술이다.
- **섀도 IT (Shadow IT)**: 회사 보안팀 허락도 안 받고 직원들이 몰래 개인 구글 드라이브나 노션 같은 걸 써서 회사 기밀을 올려버리는 통제 불능 행위다.

</details>

- **전수검사 (NGFW)**: 포트 번호를 무시하고 내용물(App-ID)과 사람(User-ID)을 엮어서 네트워크 전체를 깐깐하게 통제한다.
- **웹 저격 (WAF)**: 일반 방화벽이 보지 못하는 HTTP 헤더와 바디 안의 은밀한 악성 스크립트(XSS, SQLi)를 정밀하게 도려낸다.
- **구름 감시 (CASB)**: 사내 섀도 IT를 찾아내 접속을 차단하고, 외부 클라우드에 올라가는 문서 내용까지 까봐서(DLP) 정보 유출을 막는다.

#### 한줄 요약

- NGFW는 가방을 뒤지고, WAF는 웹 해킹 코드를 잡아내며, CASB는 직원들의 클라우드 뻘짓과 파일 유출을 잡는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DLP (데이터 유출 방지)**: "이 문서에 주민번호 100개 있네? 외부 클라우드 업로드 원천 차단!" 하고 민감 데이터의 탈출을 막는 족쇄다.
- **IdP (신원 제공자)**: 사원증(SSO) 하나로 모든 솔루션에 "이놈이 누구냐"를 증명해 주는 중앙 인증 센터다.

</details>

```text
[ 방어 계층별 보안 아키텍처 ]

[ 1. NGFW (네트워크 경계) ] ── (포트 상관없이 사내망 들어오는 놈들의 데이터 패킷를 다 까봄)
      │
      ▼
[ 2. WAF (DMZ 웹 서버 앞단) ] ── (웹으로 들어오는 놈들 중 해킹 코드 섞인 놈들 쳐냄)
      │
      ▼
[ 3. CASB (클라우드 접속 구간) ] ── (직원들이 외부 구글 드라이브로 기밀 빼돌리나 감시함)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **NGFW (차세대 방화벽)** | 네트워크 경계에서 **IP/포트 외부 래퍼를 넘어 진짜 앱 내용물을 식별해 차단함** | Network |
| **WAF (웹 방화벽)** | 웹 서버(DMZ) 바로 앞에서 **웹 해킹 코드(SQLi, XSS)를 핀셋처럼 도려냄** | Web |
| **CASB (클라우드 중개)** | 외부 클라우드 길목에서 **섀도 IT를 적발하고 문서(DLP) 유출을 틀어막음** | Cloud |
| **통합 로그 (IdP/SIEM)** | 사원증(IdP)을 연동해 **누가 어디서 뻘짓했는지 로그를 싹 다 모아서 감시함** | Mgmt |

#### 한줄 요약

- 회사 대문은 NGFW가 막고, 웹사이트 앞마당은 WAF가 지키며, 하늘(클라우드)로 날아가는 데이터는 CASB가 잡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **페이로드 (Payload)**: 패킷 외부 래퍼(헤더) 안에 들어있는 진짜 데이터 화물(내용물)이다. 방화벽들은 이 화물을 뜯어보고 차단 여부를 결정한다.

</details>

```text
[ 솔루션별 검사 및 통제 흐름 ]

┌──────────────────────────────┐
│ 1. [트래픽 목적지 및 문맥 판정]
│ ("이 패킷 어디로 가는 거냐? 사내망? 웹서버? 아니면 외부 클라우드?")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [NGFW: 네트워크 전수 검사]
│ (사내망 경계에서 App-ID/User-ID 까보고 룰셋 안 맞으면 여기서 1차 컷)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [WAF: 웹/API 악성 페이로드 심사]
│ (웹 서버로 가는 거면, HTTP 바디 까서 SQL 주입 같은 웹 해킹 공격 원천 차단)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [CASB: SaaS 섀도 IT 및 DLP 통제]
│ (외부 클라우드로 파일 올리는 거면, 내용(DLP) 까보고 승인 안 된 거면 원천 차단)
└──────────────────────────────┘
```

### 동작 원리

1. 목적지 판정: 패킷의 최종 목적지와 프로토콜 성격(웹, 일반망, 클라우드)을 파악함.
2. 네트워크 검사 (NGFW): L3~L7 세션을 열어 App-ID/User-ID 기반 룰셋으로 1차 통제함.
3. 웹 검사 (WAF): 웹 서버 대상 트래픽의 HTTP 헤더/바디를 까서 OWASP 위협을 정밀 심사함.
4. 클라우드 통제 (CASB): 외부 SaaS 접속 시 섀도 IT 차단 및 문서 내 민감정보(DLP) 유출을 방어함.

#### 한줄 요약

- 용도에 맞춰 길을 나누고 $\to$ 대문(NGFW) $\to$ 안방(WAF) $\to$ 굴뚝(CASB) 순서로 검문한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OWASP Top 10**: 전 세계에서 가장 위협적이고 많이 뚫리는 웹 해킹 공격(SQL 주입, XSS 등) 10가지를 모아둔 리스트다.

</details>

| 보안 통제 수단 | **NGFW (차세대 방화벽)** | **WAF (웹 방화벽)** | **CASB (클라우드 접근 중개)** |
|:---|:---|:---|:---|
| 핵심 특징 | **공항 입구 엑스레이 검색대** | **VIP석(웹) 전담 마크 경호원** | **해외여행(SaaS) 짐 검사 세관원** |
| 핵심 보호 영역 | 사내망 전체를 덮는 **L3~L7 네트워크 전체 IP 트래픽** | 외부로 오픈된 웹 서버의 **L7 웹 애플리케이션(HTTP/HTTPS)** 트래픽 | 직원들이 밖으로 나가는 **L7 SaaS 클라우드 서비스 및 데이터** |
| 주특기 (탐지 대상) | 포트를 속이고 들어오는 앱, 악성코드 등 **네트워크 위협 전수 방어** | OWASP Top 10(SQLi, XSS 등), 악성 봇 등 **웹 전용 해킹 저격** | 미인가 클라우드 사용(섀도 IT) 색출 및 **중요 문서 유출(DLP) 차단** |
| 치명적 한계 | 웹 트래픽의 복잡한 해킹 코드를 **정밀하게 핀셋으로 도려내진 못함** | HTTP/HTTPS 말고 다른 네트워크 프로토콜(FTP 등)은 **완전 까막눈임** | 자체 에이전트나 API 연동 안 된 **생소한 클라우드는 통제가 빡셈** |

#### 한줄 요약

- 넓은 그물은 NGFW, 웹 해킹 핀셋 방어는 WAF, 클라우드 단속은 CASB를 달아라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TLS 복호화 (Inspection)**: "데이터가 암호화돼서 못 보겠는데요?" 하는 장비들의 변명을 막기 위해, 중간에서 암호를 강제로 풀어서 내용물을 싹 다 까보는 깐깐한 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 비싼 NGFW 달았는데 **웹 게시판 해킹으로 DB가 다 털림** | NGFW는 네트워크 전반을 보지, 복잡한 웹 애플리케이션 로직 결함을 핀셋으로 방어 못 함 | 웹 서버(DMZ) 바로 앞단에 **웹 특화 전용 방어막(WAF) 필수 겹겹이 배치** | 영역별 특화 방어 및 OWASP Top 10 웹 해킹 공격 원천 차단 |
| 직원이 텔레그램이나 **개인 구글 드라이브로 기밀 도면을 빼돌림** | 사내 네트워크 밖으로 나가는 외부 SaaS 접속(섀도 IT)에 대한 통제 수단이 부재함 | 사내망 밖의 클라우드 통신까지 잡아내는 **CASB의 섀도 IT 탐지 및 DLP 연동** | 미인가 SaaS 가시성 확보 및 외부 클라우드로의 기밀 데이터 유출 완전 봉쇄 |
| 정상 접속인 척 **암호화(HTTPS) 통신 안에 악성코드와 기밀을 숨김** | 장비들이 트래픽을 까봐야 하는데, 자물쇠(SSL/TLS)로 잠겨 있어서 안을 못 봄 | NGFW/CASB 장비단에서 트래픽을 강제로 푸는 **SSL/TLS 복호화(Inspection) 적용** | 암호화 트래픽 내 은닉된 악성 코드 유입 및 기밀 유출을 위한 눈먼 지점(Blind Spot) 제거 |

#### 한줄 요약

- 웹은 WAF로 핀셋 방어하고, 클라우드 뻘짓은 CASB로 잡으며, 암호화된 트래픽도 강제로 까서 검사해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 사내망 경계망 전체 트래픽은 **NGFW** 기반 방어하고, 해킹이 빗발치는 웹 서버는 **WAF** 기반 저격하며, 직원들의 클라우드 데이터 유출은 **CASB** 기반 통제하는 빈틈없는 **계층별 심층 방어(Defense-in-Depth)** 기조를 확립함

#### 한줄 요약

- 만능 보안 장비는 없다. 성격이 다른 적을 막으려면 각 길목에 맞는 전문 문지기를 세워 통제해야 한다.
