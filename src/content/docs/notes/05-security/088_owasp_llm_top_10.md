## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **OWASP(Open Worldwide Application Security Project)**: 애플리케이션 보안 지침을 공개하는 비영리 프로젝트이다.
- **LLM(Large Language Model)**: 대규모 언어 데이터로 학습해 자연어를 이해•생성하는 모델이다.
- **RAG(Retrieval-Augmented Generation)**: 외부 자료를 검색해 모델의 생성 문맥에 결합하는 방식이다.
- **OWASP LLM Top 10 2025**: 모델•RAG•에이전트 응용의 주요 위험 열 가지를 분류한 공식 목록이다.
- **LLM 응용 위험**: 기존 웹 입력•권한 외에도 자연어 지시•검색 문맥•모델 출력•도구 행동•추론 비용에서 발생하는 위험이다.

</details>

- 정의/개념: **OWASP**가 **LLM**•**RAG**•에이전트의 **LLM 응용 위험**을 정리한 **OWASP LLM Top 10 2025** 목록이다.
- 배경/필요성: 기존 웹 보안 점검만으로는 모델•검색•도구 경계의 고유 위험을 충분히 포괄하기 어렵다.

#### 한줄 요약

- 기존 웹 보안에 더해 모델 지시•검색 문서•도구 권한•토큰 비용에서 생기는 위험을 하나의 목록으로 점검한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **판본 식별성**: 연도별로 위험 번호와 명칭이 달라질 수 있으므로 목록의 판본을 명시하여 통제•시험 항목을 일치시키는 성질이다.
- **서비스별 위협 모델**: 같은 목록이라도 서비스의 자산•신뢰 경계•도구 권한•피해 수준에 맞춰 위험 우선순위를 다시 정하는 과정이다.

</details>

- 입력부터 자원까지 전 경계 위험을 분류한다.
- **판본 식별성**으로 번호•위험명•통제 기준을 일치시킨다.
- **서비스별 위협 모델**로 자산•권한•피해에 따른 우선순위를 정한다.

#### 한줄 요약

- 같은 LLM을 써도 문서 요약 서비스와 결제 도구를 가진 에이전트는 자산•권한•피해가 달라 위험 우선순위도 달라진다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **LLM01**: 프롬프트 인젝션 위험을 다루는 항목이다.
- **LLM02**: 민감정보 노출 위험을 다루는 항목이다.
- **LLM03**: 소프트웨어 공급망 위험을 다루는 항목이다.
- **LLM04**: 데이터와 모델 오염 위험을 다루는 항목이다.
- **LLM05**: 생성 모델 출력값에 대한 검증 및 인코딩 누락으로 발생하는 서비스 취약점 위험을 규정한 항목이다.
- **LLM06**: 과도한 대리권 위험을 다루는 항목이다.
- **LLM07**: 시스템 프롬프트 누출 위험을 다루는 항목이다.
- **LLM08**: 벡터와 임베딩 취약점 위험을 다루는 항목이다.
- **LLM09**: 허위정보 위험을 다루는 항목이다.
- **LLM10**: 무제한 자원 소비 위험을 다루는 항목이다.

</details>

```text
OWASP LLM Top 10 2025
├─ 입력•출력 경계
├─ 정보•지시 경계
├─ 공급•학습 경계
├─ 검색•행동 경계
└─ 판단•자원 경계
```

| 구성요소 | 책임 |
|:---|:---|
| 입력•출력 경계 | **LLM01** 인젝션•**LLM05** 출력 처리 |
| 정보•지시 경계 | **LLM02** 노출•**LLM07** 지시 누출 |
| 공급•학습 경계 | **LLM03** 공급망•**LLM04** 오염 |
| 검색•행동 경계 | **LLM06** 대리권•**LLM08** 벡터 취약점 |
| 판단•자원 경계 | **LLM09** 허위정보•**LLM10** 자원 소비 |

#### 한줄 요약

- 악성 문서의 지시가 모델 출력을 거쳐 비밀 조회와 무승인 전송으로 이어질 수 있으므로 입력부터 실제 행동까지 연결해 본다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **공격 경로 매핑**: 각 위험 항목을 모델•데이터•검색•도구 자산과 연결하여 실제 업무 피해로 이어지는 경로를 구체화하는 활동이다.
- **잔여 위험**: 예방•탐지•복구 통제를 적용한 뒤에도 남아 있어 위험 관리자가 수용•완화•회피해야 하는 위험이다.
- **자산•신뢰 경계 확정**: 모델•데이터•검색•도구 자산과 경계별 신뢰 수준을 식별하는 단계이다.
- **LLM01~LLM10 시나리오 매핑**: 각 위험 항목을 실제 공격 경로와 업무 영향에 연결하는 단계이다.
- **예방•탐지•복구 통제 설계**: 위험별로 공격 차단•이상 발견•서비스 복원 통제를 배치하는 단계이다.
- **실제 공격•잔여 위험 평가**: 공격을 재현해 통제 실효성과 남은 위험을 측정하는 단계이다.
- **우선순위•통제 갱신**: 서비스 구조와 목록 판본 변화에 맞춰 위험 순서와 통제를 조정하는 단계이다.

</details>

```text
서비스 자산•경계
        |
        v
1. 자산•신뢰 경계 확정
        |
        v
2. LLM01~LLM10 시나리오 매핑
        |
        v
3. 예방•탐지•복구 통제 설계
        |
        v
4. 실제 공격•잔여 위험 평가
        |
        v
5. 우선순위•통제 갱신
        |
        v
   위험 처리 계획
```

### 동작 원리

1. **자산•신뢰 경계 확정**: 모델•데이터•검색•도구를 식별한다.
2. **LLM01~LLM10 시나리오 매핑**: **공격 경로 매핑**으로 업무 영향을 연결한다.
3. **예방•탐지•복구 통제 설계**: 위험별 다층 통제를 배치한다.
4. **실제 공격•잔여 위험 평가**: 재현 시험으로 통제 공백과 **잔여 위험**을 측정한다.
5. **우선순위•통제 갱신**: 구조•판본 변화를 반영한다.


#### 한줄 요약

- 체크 표시만 하지 않고 서비스의 실제 자산과 공격 경로에 항목을 매핑한 뒤 통제가 공격을 막는지 재현한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **LLM 응용 경계**: 지시•검색 문맥•출력의 신뢰를 검증하는 경계이다.
- **웹 응용 경계**: 웹 요청의 입력•인증•인가•세션 처리를 검증하는 경계이다.
- **에이전트 권한 경계**: 모델의 제안이 실제 도구 행동으로 이어질 때 승인•최소 권한•복구 가능성을 검증하는 경계이다.
- **HTTP(Hypertext Transfer Protocol)**: 웹 자원 요청과 응답의 형식•의미를 정의하는 통신 규약이다.

</details>

| 보안 경계 | 핵심 검증 대상 | 대표 위험 |
|:---|:---|:---|
| **웹 응용 경계** | **HTTP** 입력•인증•권한•세션 | 주입•인가 누락•세션 탈취 |
| **LLM 응용 경계** | 지시•**RAG** 문맥•출력 | 프롬프트 인젝션•정보 노출•허위정보 |
| **에이전트 권한 경계** | 목표•메모리•도구 승인•복구 | 과도한 대리권•비가역 행동•복구 실패 |

#### 한줄 요약

- 웹은 입력 처리, LLM은 지시와 데이터 해석, 에이전트는 모델 제안이 실제 행동으로 이어지는 권한 경계를 중점 검증한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **목록식 점검 한계**: 위험 항목에 체크만 하고 서비스의 자산•공격 경로•통제 실효성을 연결하지 않으면 고유 위험을 놓치는 문제이다.
- **레드팀**: 공격자 관점에서 서비스의 실제 공격 경로와 통제 실패를 재현하는 평가이다.
- **회귀 시험**: 통제 수정 뒤 동일•변형 공격이 다시 성공하는지 반복 확인하는 시험이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위험 목록 판본 혼용 | **OWASP LLM Top 10 2025**와 **판본 식별성** 명시 | 번호•위험명 일관성 확보 |
| **목록식 점검 한계** | **공격 경로 매핑**과 **서비스별 위협 모델** 적용 | 서비스 고유 위험 누락 방지 |
| 통제 실효성 미검증 | **레드팀**•**회귀 시험**과 **잔여 위험** 승인 | 형식 준수 통제 방지 |

#### 한줄 요약

- RAG 서비스는 문서 ACL•인젝션•출력 처리•도구 권한•자원 한도를 함께 시험하고 구조가 바뀌면 위험 순위를 다시 매긴다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **위험 분류의 활용 원칙**: OWASP 목록을 정답지가 아니라 서비스별 위협 모델과 실제 공격 검증을 빠짐없이 시작하는 공통 언어로 사용하는 원칙이다.

</details>

- **위험 분류의 활용 원칙**에 따라 자산 가치와 행동 권한이 큰 공격 경로부터 통제와 **레드팀**을 적용한다.

#### 한줄 요약

- OWASP 목록은 정답지가 아니라 서비스별 위협 모델과 실제 공격 검증을 빠짐없이 시작하기 위한 공통 분류 체계이다.
