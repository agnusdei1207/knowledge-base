## 미리 알고가기

- **오픈 월드와이드 애플리케이션 보안 프로젝트(Open Worldwide Application Security Project, OWASP)**: ‘오와스프’로 읽고 영문 핵심어의 머리글자를 딴 표기이며 공개 응용 보안 지침을 개발함
- **거대 언어 모델(Large Language Model, LLM)**: ‘엘엘엠’으로 읽고 세 영문 단어의 머리글자를 딴 표기이며 대규모 데이터로 언어를 생성·처리함
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: ‘래그’로 읽고 세 영문 핵심어의 머리글자를 딴 표기이며 검색 결과를 생성 문맥에 결합함
- **하이퍼텍스트 전송 규약(Hypertext Transfer Protocol, HTTP)**: “에이치티티피”로 읽고 영문 머리글자로 웹 요청과 응답을 전달하는 규약을 나타냄
- **에이전트**: 외부 도구를 호출해 실제 행동하는 구조
- **임베딩**: 의미를 벡터로 표현해 검색에 사용
- **OWASP LLM Top 10 2025**: LLM 응용의 주요 위험 열 가지를 2025판 번호·이름으로 분류한 지침임
- **시스템 프롬프트**: 모델의 역할·행동·제약을 서비스가 내부 문맥으로 제공하는 지시
- **과도한 대리권 (Excessive Agency)**: 에이전트에 필요 이상의 기능·권한·자율 실행 범위를 준 위험
- **무제한 소비 (Unbounded Consumption)**: 입력·출력·도구 실행에 한도가 없어 비용·자원이 고갈되는 위험
- **LLM01 같은 번호 표기**: LLM 위험군과 두 자리 순번을 붙여 판본 안의 항목을 식별함

## Ⅰ. 개요

- 정의/개념: LLM 응용의 **10대 위험·공격 예·완화 지침**
- **배경/필요성**: 웹 보안 목록만으로는 **모델·RAG·도구·비용 위험 점검 곤란**

### 쉽게 이해하기 (학습용)

- 웹 보안엔 없는 모델 지시, 검색 문서, 도구 권한, 토큰 비용 문제를 같은 설계도 위에서 점검

## Ⅱ. 특징

- **입력·출력·데이터·모델·도구·자원**의 연쇄 위험을 분류한다.
- **2025판 번호·이름**을 함께 써 판본 간 항목 혼용을 막는다.
- **위협 모델·실제 공격 검증**으로 조직별 우선순위와 통제 공백을 보완한다.

### 쉽게 이해하기 (학습용)

- 도구 권한 에이전트와 문서 요약 챗봇은 위험도와 순위가 다름

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 입력·출력 경계 | **LLM01 인젝션·LLM05 출력 처리** |
| 정보·지시 경계 | **LLM02 정보 노출·LLM07 지시 유출** |
| 공급·학습 경계 | **LLM03 공급망·LLM04 오염** |
| 검색·행동 경계 | **LLM06 대리권·LLM08 벡터 약점** |
| 판단·자원 경계 | **LLM09 허위정보·LLM10 소비** |

```text
[사용자·외부 문서] → [프롬프트·RAG] → [LLM 출력] → [응용 처리·도구]
        │                    │               │              │
   입력 인젝션         검색·오염 위험    허위·민감정보    과도한 권한
        └──────────── 공급망·자원 한도·검증 통제 ────────────┘
```

> 요약: 입력부터 도구까지 10대 위험을 경계별로 점검한다

### 쉽게 이해하기 (학습용)

- 악성 문서의 지시가 모델 출력을 거쳐 비밀 조회·무승인 전송으로 이어질 수 있어 전체 경로를 점검함

## Ⅳ. 원리 및 절차 흐름도

```text
범위확정
↓
자산식별
↓
목록매핑
↓
통제검증
↓
위험재평가
```

| 절차 | 설명 |
|:---|:---|
| 범위확정 | 모델·데이터·검색·도구 범위 정함 |
| 자산식별 | 보호 자산과 비신뢰 입력 경로 표시 |
| 목록매핑 | 공격 시나리오와 위험 항목 연결 |
| 통제검증 | 예방·탐지·복구 통제 재현 검증 |
| 위험재평가 | 구조 변경 시 우선순위 갱신 |

> 요약: 서비스 경계에 10대 위험을 매핑해 통제를 재평가한다

### 쉽게 이해하기 (학습용)

- 위험 항목을 서비스에 매핑하고 공격으로 통제 검증

## Ⅴ. 종류 및 비교

| 응용 보안 경계 | 웹 애플리케이션 | LLM 애플리케이션 | 에이전트 시스템 |
|:---|:---|:---|:---|
| 적용 기준 | 인증·권한·입출력 | 지시·데이터 분리 | 최소 권한·승인 |
| 핵심 특징 | HTTP·세션·서버 처리 | 프롬프트·검색·출력 경계 | 목표·메모리·도구 실행 |
| 한계 | 주입·인가·세션 취약점 | 인젝션·노출·오염·허위정보 | 과도한 대리권·복구 실패 |

> 요약: 웹·LLM·에이전트는 통제할 실행 경계가 다르다

### 쉽게 이해하기 (학습용)

- 웹은 입력 처리, LLM은 지시 해석, 에이전트는 행동 검증

## Ⅵ. 실무 사례

1. RAG는 **검색 권한·인젝션·출력 처리 검증**
2. 에이전트는 **도구 최소 권한·고위험 행동 승인**

### 쉽게 이해하기 (학습용)

- RAG는 문서 권한부터 모델 출력의 후속 처리까지 하나의 공격 경로로 시험한다.
- 에이전트는 모델 제안과 실제 도구 권한을 분리하고 고위험 행동을 승인한다.

## Ⅶ. 결론

- LLM 위험 분류는 **Top 10**, 우선순위는 **서비스 위협 모델**

### 쉽게 이해하기 (학습용)

- 각 서비스의 자산·권한·비용에서 실제 공격과 통제 파악 필요
