## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **보안 주장 마크업 언어(Security Assertion Markup Language, SAML) 2.0**: 인증 결과와 속성을 XML 주장으로 전달하는 연합 인증 표준이다.
- **확장 가능 마크업 언어(Extensible Markup Language, XML)**: 구조화된 문서를 표현•교환하는 마크업 언어이다.
- **통합 인증(Single Sign-On, SSO)**: 한 번의 인증으로 여러 연계 서비스에 접속하게 하는 인증 방식이다.

</details>

- 정의/개념: **SAML 2.0**은 서명된 **XML** 주장으로 인증 결과와 속성을 전달한다.
- 배경/필요성: **SSO**는 서비스마다 중복 계정과 자격 증명을 관리하는 부담을 줄인다.

#### 한줄 요약

- 중앙 신원 기관이 서명한 소개장을 보내면 서비스는 발급자뿐 아니라 자기에게 보낸 현재 요청의 문서인지 확인한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **Assertion**: 사용자•인증•조건을 담아 전달하는 SAML 주장 문서이다.
- **Metadata**: 기관 식별자•수신 주소•인증서 등 연합 신뢰 설정을 담는 문서이다.
- **신원 제공자(Identity Provider, IdP)**: 사용자를 인증하고 SAML 주장을 발급하는 기관이다.
- **서비스 제공자(Service Provider, SP)**: SAML 주장을 검증하고 서비스를 제공하는 기관이다.
- **식별자(Identifier, ID)**: 요청과 응답을 고유하게 구분하는 값이다.
- **Recipient**: SAML 응답을 수신하도록 지정된 주소이다.
- **재전송 공격**: 이미 사용한 정상 인증 응답을 다시 제출하는 공격이다.

</details>

- **IdP**와 **SP**는 **Metadata**로 식별자•주소•인증서를 사전 교환한다.
- **Assertion**을 통한 사용자•속성•대상•시간•요청 결속을 전달한다.
- 서명 요소•대상•시간•요청•응답 **ID**와 **Recipient**를 검증해 **재전송 공격**을 차단한다.

#### 한줄 요약

- 서명만 진짜여도 다른 서비스용이거나 이미 사용한 소개장이면 로그인을 허용해서는 안 된다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **로컬 세션**: SP가 SAML 검증을 완료한 뒤 자체적으로 생성하는 로그인 상태이다.

</details>

```text
SAML 연합 인증 구조
├─ 사용자 브라우저: 요청•응답 중계
├─ SP: 주장 검증•로컬 세션 생성
├─ IdP: 사용자 인증•응답 서명
├─ SAML Assertion: 신원•속성•조건 전달
└─ 메타데이터•검증 체계: 신뢰•재전송 관리
```

| 구성요소 | 책임 |
|:---|:---|
| 사용자 브라우저 | 요청•응답 중계 |
| SP | **SP**가 주장 검증•**로컬 세션** 생성 |
| IdP | **IdP**가 사용자 인증•응답 서명 |
| SAML Assertion | **Assertion**으로 신원•속성•조건 전달 |
| 메타데이터•검증 체계 | **Metadata**의 신뢰 정보•재전송 관리 |

#### 한줄 요약

- 브라우저가 문서를 운반하고 IdP가 서명하며 SP가 등록된 신뢰 정보와 조건을 기준으로 최종 로그인 여부를 정한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **인증 요청(Authentication Request, AuthnRequest)**: SP가 IdP에 사용자 인증을 요구하는 SAML 메시지이다.
- **응답 ID**: 요청•응답 결속과 중복 사용 여부를 판별하는 고유 식별자이다.
- **SAML AuthnRequest 생성**: SP가 요청 ID•IdP 목적지•반환 주소를 포함한 인증 요청을 만드는 단계이다.
- **사용자 신원 인증**: IdP가 등록된 인증기로 사용자를 확인하는 단계이다.
- **Assertion 조건•서명 생성**: 사용자 신원•대상•시간 조건을 담은 주장에 서명하는 단계이다.
- **서명•대상•요청 결속 검증**: SP가 서명된 처리 요소와 최초 요청•대상•수신자의 일치를 확인하는 단계이다.
- **재전송 차단•로컬 세션 생성**: 응답 ID 중복을 거부하고 신규 응답에만 세션을 발급하는 단계이다.

</details>

```text
서비스 접근
    |
    v
1. SAML AuthnRequest 생성
    |
    v
2. 사용자 신원 인증
    |
    v
3. Assertion 조건•서명 생성
    |
    v
4. 서명•대상•요청 결속 검증
    |
    v
5. 재전송 차단•로컬 세션 생성
    |
    +-- 응답 ID 중복 -- 로그인 거부
    |
    +-- 신규 응답 ID -- 로컬 세션 발급
```

### 동작 원리

1. **SAML AuthnRequest 생성**: 요청 ID•IdP 목적지•반환 주소를 구성해 SAML AuthnRequest를 생성한다.
2. **사용자 신원 인증**: IdP가 등록 인증기로 사용자 신원을 인증한다.
3. **Assertion 조건•서명 생성**: 신원•대상•시간 조건을 담아 Assertion 조건•서명을 생성한다.
4. **서명•대상•요청 결속 검증**: 처리 요소와 최초 요청에 대해 서명•대상•요청 결속을 검증한다.
5. **재전송 차단•로컬 세션 생성**: 응답 ID 중복을 차단하고 신규 응답에 로컬 세션을 생성한다.


#### 한줄 요약

- SP가 만든 **AuthnRequest**를 IdP가 확인해 서명 응답을 만들고 **응답 ID**로 중복 사용을 검사한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **SP 시작**: 서비스의 인증 요청에서 연합 인증 흐름이 출발하는 방식이다.
- **IdP 시작**: 중앙 신원 포털의 인증 응답에서 연합 인증 흐름이 출발하는 방식이다.

</details>

| SAML 인증 시작 방식 | 공통 | SP 시작 | IdP 시작 |
|:---|:---|:---|:---|
| 적용 기준 | 기업 웹 SSO 연계 | 요청•응답 결합 필요 | 중앙 포털 중심 접근 |
| 핵심 특징 | XML 주장 연합 인증 | **SP 시작**의 요청 기반 인증 | **IdP 시작**의 포털 기반 인증 |
| 한계 | 서명•대상 오검증 | 요청 상태 변조 | 무요청 응답의 재전송 |

#### 한줄 요약

- SP 시작은 질문과 답을 묶기 쉽고 IdP 시작은 별도 질문이 없어 응답의 목적지와 재사용을 더 엄격히 통제해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **OASIS SAML 2.0 Core**: SAML 주장•프로토콜•조건•서명 처리의 핵심 구문과 의미를 정의하는 표준이다.
- **XML 서명 래핑 공격**: 서명된 요소와 애플리케이션이 실제 처리하는 요소의 차이를 악용해 위조 내용을 수용하게 하는 공격이다.
- **W3C XML Signature 1.1**: XML 문서의 서명 대상 요소와 검증 방법을 정의하는 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 주장 대상•시간•요청을 잘못 검증하면 다른 서비스용 주장 수용 | **OASIS SAML 2.0 Core** 준수 | 대상•시간•요청 결속 확보 |
| 서명 요소와 처리 요소가 다르면 **XML 서명 래핑 공격** 성공 | **W3C XML Signature 1.1** 검증 | 서명•처리 요소 일치 |
| 요청 없는 응답이나 중복 응답을 허용하면 재전송 로그인 | **응답 ID** 저장•짧은 유효시간 적용 | 재전송과 세션 탈취 방지 |

#### 한줄 요약

- 서비스 제공자는 IdP가 서명한 정확한 Assertion의 대상•수신자•유효시간을 검증한 뒤에만 기업 사용자의 세션을 생성한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **요청 결속**: SAML 응답을 최초 요청의 ID•대상•수신자와 연결해 다른 요청이나 서비스에서 재사용하지 못하게 하는 검증 원칙이다.
</details>

- **요청 결속**이 필요하면 **SP 시작**, 중앙 포털은 **IdP 시작**과 응답 ID 재사용 차단을 적용한다.

#### 한줄 요약

- SAML SSO는 문서의 서명뿐 아니라 누가 누구에게 언제 어떤 요청의 답으로 보냈는지를 모두 확인해야 안전하다.
