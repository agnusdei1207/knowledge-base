## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 성숙도**: 보안 관행이 반복•측정•개선되는 조직 역량의 정도이다.
- **현재•목표 역량 평가**: 실행 증거로 현재 수준을 확인하고 업무 위험과 의무에 맞는 목표 수준을 정하는 평가 체계이다.

</details>

- 정의/개념: **보안 성숙도**의 현재와 목표 역량을 증거로 정하는 **현재•목표 역량 평가**이다.
- 배경/필요성: 도구 보유 수만으로는 보안 관행의 반복 역량과 개선 효과를 판단하기 어렵다.

#### 한줄 요약

- 도구 수보다 **관행의 반복·측정·개선** 평가

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **역량 수준**: 보안 목적을 달성하는 조직의 능력 단계이다.
- **성숙도 수준**: 보안 관행이 제도화된 정도를 나타내는 단계이다.
- **위험 기반 우선순위화**: 단순히 점수가 낮은 항목보다 업무 영향과 의존성이 큰 역량 격차를 먼저 개선하는 방식이다.
- **지속 개선 검증**: 반복 평가와 성과 지표를 이용해 개선 활동이 실제 위험을 줄였는지 확인하는 과정이다.

</details>

- **역량 수준**과 **성숙도 수준**을 실행 증거로 평가한다.
- 현재•목표 격차의 **위험 기반 우선순위화**가 핵심이다.
- 반복 평가•성과 지표의 **지속 개선 검증**이 핵심이다.

#### 한줄 요약

- 낮은 점수를 모두 먼저 고치지 않고 업무 위험과 의존성이 큰 격차부터 개선하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **현재•목표 프로파일**: 증거로 확인한 현재 역량 상태와 업무 위험•의무에 맞춰 정한 목표 상태이다.
- **격차•의존성 로드맵**: 현재와 목표의 차이를 위험•선후관계에 따라 배열하고 책임자와 일정을 지정한 개선 계획이다.

</details>

```text
보안 성숙도 평가 체계
├─ 평가 목적•위험 범위
├─ 영역•관행•증거 기준
├─ 현재•목표 프로파일
├─ 격차•의존성 로드맵
└─ 성과 지표•주기 재평가
```

가지의 의미: 평가 범위와 증거에서 개선 로드맵•재평가까지의 정적 구성을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 평가 목적•위험 범위 | 자산•업무•법적 의무•경계 |
| 영역•관행•증거 기준 | 행위•표본•평가 척도 |
| 현재•목표 프로파일 | **현재•목표 프로파일**로 목표 수준 설정 |
| 격차•의존성 로드맵 | **격차•의존성 로드맵**으로 책임•일정 설정 |
| 성과 지표•주기 재평가 | 효과•잔여위험•목표 갱신 |

#### 한줄 요약

- 평가·증거·책임·지표를 **조직 역량으로 연결**

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **증거 기반 평가**: 인터뷰뿐 아니라 실행 기록•성과 표본으로 관행의 반복 수행 여부를 확인하는 방식이다.
- **잔여위험 재평가**: 개선 조치를 수행한 뒤에도 남은 위험과 목표 수준의 적정성을 다시 판단하는 활동이다.
- **평가 목적•범위•모델 선정**: 자산•업무•위험에 맞는 평가 단위와 모델을 정하는 단계이다.
- **표본 기간•실행 증거 검증**: 기록•인터뷰•성과 표본으로 관행의 반복 여부를 확인하는 단계이다.
- **현재 수준•목표 프로파일 판정**: 증거로 현재 상태를 확인하고 위험 허용선에 맞는 목표를 정하는 단계이다.
- **위험•의존성 기반 로드맵 수립**: 격차의 위험•선후관계에 따라 과제•책임•일정을 배치하는 단계이다.
- **성과 측정•잔여위험 재평가**: 개선 효과와 남은 위험을 확인해 목표 상태를 갱신하는 단계이다.

</details>

```text
평가 목적•업무 위험
         │
         ▼
1. 평가 목적·범위·모델 선정
         │
         ▼
2. 표본 기간·실행 증거 검증
         │
         ▼
3. 현재 수준·목표 프로파일 판정
         │
         ▼
4. 위험·의존성 기반 로드맵 수립
         │
         ▼
5. 성과 측정·잔여위험 재평가
         │
         ▼
개선 효과•투자 결과 반영
```

### 동작 원리

1. 평가 목적·범위·모델 선정: 평가 단위 확정
2. 표본 기간·실행 증거 검증: 반복 수행 확인
3. 현재 수준·목표 프로파일 판정: 허용선 설정
4. 위험·의존성 기반 로드맵 수립: 책임·투자 배정
5. 성과 측정·잔여위험 재평가: 목표 상태 갱신

#### 한줄 요약

- 기간별 기록·결과로 **반복 수행 여부 검증**

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **개방형 웹 응용 보안 프로젝트(Open Worldwide Application Security Project, OWASP)**: 웹 응용 보안 공개 프로젝트이다.
- **소프트웨어 보증 성숙도 모델(Software Assurance Maturity Model, SAMM)**: 소프트웨어 보증 역량 평가 모델이다.
- **보안 구축 성숙도 모델(Building Security In Maturity Model, BSIMM)**: 관찰 기반 소프트웨어 보안 벤치마킹 모델이다.
- **미국 에너지부(Department of Energy, DOE)**: 미국 에너지 정책을 담당하는 정부 부처이다.
- **사이버보안 역량 성숙도 모델(Cybersecurity Capability Maturity Model, C2M2)**: 전사 사이버보안 역량 평가 모델이다.
- **성숙도 지표 수준(Maturity Indicator Level, MIL)**: C2M2 관행의 제도화 단계를 나타내는 척도이다.
- **정보기술(Information Technology, IT)**: 업무 정보를 처리•저장•전송하는 기술이다.
- **운영기술(Operational Technology, OT)**: 물리 공정•설비를 감시•제어하는 기술이다.

</details>

| 성숙도 모델 | OWASP SAMM v2 | BSIMM | DOE C2M2 v2.1 |
|:---|:---|:---|:---|
| 적용 기준 | 소프트웨어 보증 로드맵 | 실제 활동 벤치마킹 | 전사 IT•OT 역량 개선 |
| 핵심 특징 | **OWASP**의 **SAMM** | **BSIMM** 관찰 활동 | **DOE**의 **C2M2**와 **MIL** |
| 한계 | 맥락 없는 일률 목표 | 활동 수와 효과 불일치 | 점수와 위험 분리 |

- 전사 평가에는 **IT**와 **OT** 범위를 함께 명시한다.

> 요약: 범위•목적에 맞는 모델로 증거 기반 격차를 개선하는 것이 핵심이다.

#### 한줄 요약

- 모델별 범위와 척도가 달라 점수를 직접 비교하지 말고 평가 목적에 맞춰 선택하는 것이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **미국 국립표준기술연구소(National Institute of Standards and Technology, NIST)**: 미국의 기술 표준 기관이다.
- **사이버보안 프레임워크(Cybersecurity Framework, CSF)**: 사이버보안 위험관리 결과 체계이다.
- **특별간행물(Special Publication, SP)**: NIST가 발행하는 기술 지침이다.
- **NIST SP 1302**: CSF 조직 프로파일 활용 지침이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소프트웨어 보증 역량 개선 | OWASP SAMM 적용 | 단계 로드맵 확보 |
| 전사 IT•OT 역량 평가 | DOE C2M2 적용 | 영역별 격차 식별 |
| 위험관리 성숙도 표현 | **NIST**의 **CSF**, **SP**, **NIST SP 1302** 적용 | 프로파일•티어 연계 |

#### 한줄 요약

- 금융사는 SAMM으로 개발보안을 평가하고 고위험 관행의 증거 격차부터 투자하는 것이 핵심이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 기반 로드맵**: 낮은 점수 전체가 아니라 업무 위험과 의존성이 큰 역량 격차부터 개선하는 계획이다.
- **모델 선택**: 소프트웨어 보증은 OWASP SAMM, 전사 IT•OT 역량은 DOE C2M2처럼 평가 범위와 목적에 맞는 성숙도 모델을 적용하는 결정이다.

</details>

- **모델 선택** 후 **위험 기반 로드맵**에 따라 고위험 격차부터 투자한다.

#### 한줄 요약

- 성숙도 점수는 성적표가 아니라 다음에 무엇을 왜 개선할지 합의하는 출발점이다.
