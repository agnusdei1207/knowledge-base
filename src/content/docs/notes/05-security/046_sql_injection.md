## 미리 알고가기

- **SQL (Structured Query Language)**: [읽기: 에스큐엘; 표기 이유: 영문 머리글자] 관계형 데이터베이스의 조회·삽입·수정·삭제를 지시하는 언어
- **SQL 인젝션**: [읽기: 에스큐엘; 표기 이유: 영문 머리글자] 외부 입력이 SQL의 값이 아니라 명령 구조로 해석돼 질의 의미를 바꾸는 취약점
- **준비된 질의 (Prepared Statement)**: [읽기: 준비된 질의; 표기 이유: 한글명 뒤 영문 원어 병기] SQL 구조를 먼저 고정하고 외부 입력은 별도 값으로 전달하는 방식
- **값 바인딩**: [읽기: 값 바인딩; 표기 이유: 한국어 통용어 표기] 외부 입력을 SQL 구문이 아닌 매개변수 값으로 결합하는 처리
- **ORM (Object-Relational Mapping)**: [읽기: 오알엠; 표기 이유: 영문 머리글자] 프로그램 객체와 데이터베이스 테이블·질의를 연결하는 기술
- **인밴드**: [읽기: 인밴드; 표기 이유: 한국어 통용어 표기] 공격 결과가 원래 웹 응답으로 직접 돌아오는 SQL 인젝션
- **블라인드**: [읽기: 블라인드; 표기 이유: 한국어 통용어 표기] 결과 내용 없이 참·거짓이나 응답 시간 차이로 데이터를 추론하는 SQL 인젝션
- **아웃오브밴드**: [읽기: 아웃오브밴드; 표기 이유: 한국어 통용어 표기] 데이터베이스가 DNS·HTTP 등 별도 통신 경로로 결과를 보내게 하는 SQL 인젝션
- **WAF (Web Application Firewall)**: [읽기: 더블유에이에프; 표기 이유: 영문 머리글자] 웹 요청의 공격 패턴을 검사·차단하는 방화벽


- **흐름 기호(↓·→·X)**: [읽기: 흐름 기호; 표기 이유: 한글명 뒤 영문 원어 병기] 아래로·다음으로·차단으로 읽으며 순서·분기·금지를 나타냄
## Ⅰ. 개요

- **정의/개념**: 입력이 SQL 구조를 바꾸는 주입 취약점임
- **배경/필요성**: 변조 질의는 데이터와 DB 권한을 침해함

### 쉽게 이해하기 (학습용)

- 입력을 값이 아닌 SQL 구문으로 해석하면 질의와 권한이 공격자에게 바뀐다.

## Ⅱ. 특징

- 문자열 결합 SQL에서 입력이 구문 경계를 바꾼다.
- 응답·오류·시간 차이가 데이터 추론 경로가 된다.
- 준비된 질의가 SQL 구조와 입력값을 분리한다.
- DB 계정 권한이 침해 영향의 상한을 정한다.

### 쉽게 이해하기 (학습용)

- 값 바인딩은 구조를 고정하며 WAF와 이스케이프는 보조 통제이다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 비신뢰 입력 | 폼·API·저장 데이터에서 유입 |
| 질의 생성 | 문자열 결합이 SQL 구조 오염 |
| DB 드라이버 | 값 바인딩으로 입력 경계 고정 |
| DB 계정 | 허용 스키마로 피해 범위 제한 |
| 오류·감사 | 이상 질의 추적 및 노출 차단 |

```text
[폼·API 입력] → [응용 질의 생성] → [DB 드라이버] → [DB 계정·스키마]
                     │
              준비된 질의·값 바인딩
                     ↓
             SQL 구조와 입력 값 분리
```

### 쉽게 이해하기 (학습용)

- 준비된 질의와 최소 권한이 주입 가능성과 피해 범위를 각각 줄인다.

## Ⅳ. 원리 및 절차 흐름도

```text
입력추적
   ↓
매개변수화
   ↓
식별자제한
   ↓
권한통제
   ↓
검증감시
```

| 절차 | 설명 |
|:---|:---|
| 입력추적 | 외부 입력부터 SQL 실행점 추적함 |
| 매개변수화 | 준비된 질의로 구조와 값 분리함 |
| 식별자제한 | 테이블과 열 이름 허용목록 매핑함 |
| 권한통제 | 최소 권한 계정과 오류 화면 통제함 |
| 검증감시 | 취약점 검증과 실행 로그 감사함 |

> 요약: 입력 추적 후 파라미터 분리 및 권한 제한함

### 쉽게 이해하기 (학습용)

- 입력부터 실행점까지 추적해 값은 바인딩하고 식별자는 허용목록으로 제한한다.

## Ⅴ. 종류 및 비교

| 비교축 | 인밴드 | 블라인드 | 아웃오브밴드 |
|:---|:---|:---|:---|
| 핵심 특징 | 같은 응답에서 오류·결과 노출 | 참·거짓·시간 차이로 결과 추론 | DNS·HTTP 등 별도 경로로 결과 유출 |
| 적용 기준 | 결과가 노출될 때 | 결과를 관찰할 때 | 외부 통신 가능시 |
| 주요 위험 | 대량 데이터가 즉시 유출됨 | 느리지만 응답만으로 정보 추출 | 내부 DB에서 외부로 우회 통신 발생 |

> 요약: 공격 경로에 따라 인밴드·블라인드·아웃오브밴드 구분함

### 쉽게 이해하기 (학습용)

- 결과가 돌아오는 경로에 따라 인밴드·블라인드·외부 경로로 나뉜다.

## Ⅵ. 실무 사례

- 프로시저 내부 동적 SQL 문자열 결합 금지
- ORM 사용 시 원시 질의와 동적 구문 검토
- 이스케이프/WAF는 보조 통제로만 적용
- DB 계정의 불필요한 관리 권한 제거

### 쉽게 이해하기 (학습용)

- 프로시저 안에서도 동적 SQL 문자열 결합을 금지한다.
- ORM의 원시 질의와 동적 식별자 사용을 검토한다.
- 이스케이프와 WAF는 우회 가능한 보조 통제로 둔다.
- DB 계정에서 불필요한 관리·파일·망 권한을 제거한다.

## Ⅶ. 결론

- 값 바인딩과 최소 DB 권한을 함께 적용함

### 쉽게 이해하기 (학습용)

- SQL 구조와 값을 분리하고 DB 최소 권한으로 피해 범위를 줄인다.
