## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **구조화 질의 언어(Structured Query Language, SQL) 인젝션**: 클라이언트의 조작된 비신뢰 입력값이 백엔드 DB의 SQL 쿼리 구문 해석기로 인입되어 쿼리 구조와 의미를 무단 변조하는 주입 공격.

</details>

- 정의/개념: 외부 입력이 SQL 구문으로 실행되는 **SQL 인젝션**
- 배경/필요성: 문자열 결합은 **구문-데이터 경계**를 붕괴

#### 한줄 요약

- 외부 입력이 SQL 명령 구문으로 오인 실행되지 않도록 쿼리 구조와 데이터 채널을 물리적으로 분리함.

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **준비된 질의(PreparedStatement)**: DB 엔진에서 SQL 쿼리 구조를 미리 컴파일하여 고정하고 입력값을 매개변수 파라미터로 처리하는 기술.
- **값 바인딩(Parameter Binding)**: 사용자 입력값을 명령어가 아닌 pure 데이터값으로만 매핑 처리하는 기법.
- **응답 기반 추론(In-band / Error-based / Boolean-based)**: 정상 결과나 시스템 에러 메세지를 바탕으로 데이터를 탈취하는 기법.
- **시간차 기반 추론(Time-based Blind)**: SLEEP() 등 시간 지연 연산자의 동작 여부로 참/거짓 판단 및 데이터를 유출하는 기법.
- **웹 애플리케이션 방화벽(Web Application Firewall, WAF)**: HTTP 요청 내 알려진 SQL 공격 시그니처 패턴을 검출 및 차단하는 보조 장비.

</details>

- 동적 문자열 연결 시 쿼리 구문 해석 문맥을 상실하여 권한 오용을 유발.
- **응답 기반 추론**, **오류 기반 추론**, **시간차 기반 추론** 기법을 통한 오프라인/블라인드 데이터 유출.
- **준비된 질의(PreparedStatement)** 및 **값 바인딩(Parameter Binding)**에 의한 입력 구문 구조적 분리.

#### 한줄 요약

- PreparedStatement 기반 값 바인딩으로 구문을 고정하며, WAF 및 특수문자 이스케이프는 차선책으로 운용함.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **최소 권한 DB 계정(Least Privilege DB Account)**: 애플리케이션이 사용할 DB 계정의 테이블 조회/수정 권한 및 시스템 저장프로시저 접근 권한을 최적 최소화한 계정.
- **데이터베이스(Database, DB)**: 백엔드 데이터 저장소로 쿼리 결과를 실행 및 반환하는 주체.
- **허용목록(Allowlist)**: 매개변수 바인딩이 안 되는 동적 테이블명/정렬 조건 열 이름을 승인된 사전으로 제한하는 검증 기법.

</details>

```text
SQL 실행 경계
├─ 비신뢰 입력: 외부 값 유입
├─ 질의 생성: SQL 구조•입력값 분리
├─ DB 드라이버: 매개변수 값 바인딩
├─ DB 계정: 허용 스키마•연산 제한
└─ 오류•감사: 이상 질의 추적•오류 차단
```

| 구성요소 | 책임 |
|:---|:---|
| 비신뢰 입력 | 폼, API 및 쿠키 등 외부 데이터 유입 접점 |
| 질의 생성 | 입력값과 **DB**가 해석할 SQL 구문 구조를 분리 |
| DB 드라이버 | **값 바인딩**을 통해 입력값을 pure 파라미터로 매핑 |
| DB 계정 | **최소 권한 DB 계정**을 적용하여 침해 시 피해 범위를 제한 |
| 오류•감사 | 상세 DB 시스템 에러 노출 통제 및 쿼리 이력 감사 |

#### 한줄 요약

- 준비된 질의와 최소 권한 DB 계정을 적용하여 취약점 발생 가능성과 영향 범위를 동시 억제함.

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **구조•값 분리(Structure & Data Separation)**: SQL 쿼리의 컴파일된 구조체와 사용자 입력을 별도 바이트 채널로 전송하는 안전 원칙.
- **준비된 SQL 구조 생성(Query Pre-compilation)**: DB에서 SQL 문법 구조를 사전 컴파일하는 단계.
- **입력값 바인딩(Value Binding)**: 입력 데이터를 매개변수 위치에 안전하게 맵핑하는 단계.
- **SQL 구조 컴파일•값 처리(Execution Engine)**: 구문 파싱 없이 매개변수로만 처리하는 단계.
- **최소 권한 질의 실행(Least Privilege Execution)**: 해당 계정이 승인받은 연산만 집행하는 단계.
- **질의•오류 감사 기록(Audit Logging)**: 에러 억제 및 이상 질의 로그를 보존하는 단계.

</details>

```text
외부 입력
    │
    ▼
1. 준비된 SQL 구조 생성
    │
    ▼
2. 입력값 바인딩
    │
    ▼
3. SQL 구조 컴파일•값 처리
    │
    ▼
4. 최소 권한 질의 실행
    │
    ▼
5. 질의•오류 감사 기록
    │
    ▼
제한된 질의 결과
```

### 동작 원리

1. **준비된 SQL 구조 생성**: DB에서 SQL 실행계획 및 쿼리 아키텍처 사전 컴파일.
2. **입력값 바인딩**: 입력값을 명령어 구문이 아닌 매개변수로 안전 전달.
3. **SQL 구조 컴파일•값 처리**: 구문 재파싱 없이 고정된 구조에서 데이터값만 매치.
4. **최소 권한 질의 실행**: 애플리케이션 전용 최소 권한 계정으로 쿼리 집행.
5. **질의•오류 감사 기록**: 상세 시스템 오류 노출 방지 및 이상 질의 로그 저장.

#### 한줄 요약

- PreparedStatement 쿼리 준비부터 입력값 바인딩, 최소 권한 실행 및 오류 숨김을 순차 집행함.

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **인밴드(In-band / Classic SQLi)**: 애플리케이션의 일반적인 HTTP 응답 채널을 통해 추출된 데이터나 오류를 직접 수신하는 공격.
- **블라인드(Blind SQLi)**: HTTP 응답 메시지에 데이터가 직접 출력되지 않으나, True/False 반응이나 시간 지연을 이용해 데이터를 복원하는 공격.
- **아웃오브밴드(Out-of-band / OAST)**: DNS 질의, HTTP 요청 등 DB 서버가 외부로 직접 전송하는 별도의 네트워크 채널을 악용하는 공격.

</details>

| SQL 인젝션 유형 | 인밴드 | 블라인드 | 아웃오브밴드 |
|:---|:---|:---|:---|
| 적용 기준 | 결과가 직접 노출될 때 | 응답 차이를 관찰할 수 있을 때 | 외부 통신이 가능할 때 |
| 핵심 특징 | 동일 응답 결과 노출 | 응답 차이로 결과 추론 | **DNS/HTTP 외부 경로** 같은 별도 통신 경로 유출 |
| 한계 | 대량 데이터 즉시 유출 | 느리지만 응답만으로 추론 | 내부 DB에 별도 외부 통신 경로 필요 |

#### 한줄 요약

- 데이터 유출 방식에 따라 인밴드, 반응/시간차 분석 블라인드, 외부 쿼리 발생 아웃오브밴드로 구분함.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **MITRE CWE-89**: SQL 명령에 사용되는 특별 요소의 부적절한 무력화(SQL Injection) 취약점 명세.
- **OWASP ASVS 5.0.0**: 쿼리 인젝션 및 매개변수 검증 요구사항을 규정한 최신 표준 명세서.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동적 문자열 연결 시 쿼리 변조 | **MITRE CWE-89** 준수 정적 분석 및 PreparedStatement 적용 | 입력의 구문 파싱 완전 차단 |
| 개발자별 입력 검증 수준 편차 | **OWASP ASVS 5.0.0** 인젝션 통제 수립 | 조직적 입력/쿼리 분리 검증 확보 |
| 동적 식별자 및 권한 과다 | **허용목록** 및 **최소 권한 DB 계정** 적용 | 식별자 주입 방지 및 침해 시 관제 한계 설정 |

#### 한줄 요약

- 문자열을 직접 연결하지 않고 PreparedStatement를 사용하며, 동적 테이블/컬럼명은 허용목록으로 통제함.

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **SQL 인젝션 통제 선택 기준**: 사용자 값 입력에는 PreparedStatement, 동적 인자에는 Allowlist, DB 시스템 계정에는 최소 권한을 다각 적용하는 방어 원칙.

</details>

- **SQL 인젝션 통제 선택 기준**에 따라 사용자 값은 **준비된 질의**와 **값 바인딩**, 동적 식별자는 **허용목록**, DB 계정은 **최소 권한 DB 계정** 적용.

#### 한줄 요약

- 값은 **준비된 질의**, 동적 식별자는 **허용목록** 적용
