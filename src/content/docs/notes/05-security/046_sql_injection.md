## 미리 알고가기

- **구조화 질의 언어(Structured Query Language, SQL)**: 관계형 데이터베이스의 데이터를 조회·변경하는 질의 언어이다.
- **SQL 인젝션(SQL Injection, 에스큐엘 인젝션)**: 외부 입력이 값이 아닌 SQL 명령 구조로 해석돼 질의 의미를 바꾸는 취약점
- **준비된 질의(Prepared Statement)**: SQL 구조를 먼저 고정하고 외부 입력을 별도 매개변수 값으로 전달하는 방식
- **값 바인딩**: 외부 입력을 SQL 구문이 아닌 매개변수 값으로 결합하는 처리
- **ORM(Object-Relational Mapping, 오알엠)**: 객체와 데이터베이스 테이블·질의를 연결하는 기술이며, 문자열 결합 사용 시 주입을 자동 방지하지 못함
- **인밴드**: 공격 결과가 원래 웹 응답으로 직접 돌아오는 방식
- **블라인드**: 참·거짓이나 응답 시간 차이로 결과를 추론하는 방식
- **아웃오브밴드**: DNS·HTTP 등 별도 통신 경로로 결과를 유출하는 방식
- **WAF(Web Application Firewall, 와프)**: 웹 요청의 공격 패턴을 검사·차단하는 보조 통제


- **흐름 기호(↓·→·X)**: 아래·다음·차단의 절차 방향과 금지를 표시
## Ⅰ. 개요

- 정의/개념: 입력이 SQL 구조를 바꾸는 주입 취약점임
- 기존 한계: 문자열 결합 질의는 입력과 SQL 구조를 미분리
- **배경/필요성**: 질의 구조 고정과 DB 최소 권한 적용

### 쉽게 이해하기 (학습용)

- 입력을 값이 아닌 SQL 구문으로 해석하면 질의와 권한이 공격자에게 바뀐다.

## Ⅱ. 특징

- 문자열 결합 SQL에서 입력이 구문 경계를 바꾼다.
- 응답·오류·시간 차이가 데이터 추론 경로가 된다.
- 준비된 질의가 SQL 구조와 입력값을 분리한다.
- DB 계정 권한이 침해 영향의 상한을 정한다.

### 쉽게 이해하기 (학습용)

- 값 바인딩은 구조를 고정하며 WAF와 이스케이프는 보조 통제이다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 비신뢰 입력 | 폼·API·저장 데이터에서 유입 |
| 질의 생성 | 문자열 결합이 SQL 구조 오염 |
| DB 드라이버 | 값 바인딩으로 입력 경계 고정 |
| DB 계정 | 허용 스키마로 피해 범위 제한 |
| 오류·감사 | 이상 질의 추적 및 노출 차단 |

```text
[폼·API 입력] → [응용 질의 생성] → [DB 드라이버] → [DB 계정·스키마]
                     │
              준비된 질의·값 바인딩
                     ↓
             SQL 구조와 입력 값 분리
```

### 쉽게 이해하기 (학습용)

- 준비된 질의와 최소 권한이 주입 가능성과 피해 범위를 각각 줄인다.

## Ⅳ. 원리 및 절차 흐름도

```text
입력추적
   ↓
매개변수화
   ↓
식별자제한
   ↓
권한통제
   ↓
검증감시
```

| 절차 | 설명 |
|:---|:---|
| 입력추적 | 외부 입력부터 SQL 실행점 추적함 |
| 매개변수화 | 준비된 질의로 구조와 값 분리함 |
| 식별자제한 | 테이블과 열 이름 허용목록 매핑함 |
| 권한통제 | 최소 권한 계정과 오류 화면 통제함 |
| 검증감시 | 취약점 검증과 실행 로그 감사함 |

> 요약: 입력 추적 후 파라미터 분리 및 권한 제한함

### 쉽게 이해하기 (학습용)

- 입력부터 실행점까지 추적해 값은 바인딩하고 식별자는 허용목록으로 제한한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 인밴드 | 블라인드 | 아웃오브밴드 |
|:---|:---|:---|:---|
| 적용 기준 | 결과가 노출될 때 | 결과를 관찰할 때 | 외부 통신 가능시 |
| 핵심 특징 | 같은 응답에서 오류·결과 노출 | 참·거짓·시간 차이로 결과 추론 | 별도 통신 경로로 결과 유출 |
| 한계 | 대량 데이터 즉시 유출 | 느리지만 응답만으로 정보 추출 | 내부 DB의 외부 우회 통신 |

> 요약: 공격 경로에 따라 인밴드·블라인드·아웃오브밴드 구분함

### 쉽게 이해하기 (학습용)

- 결과가 돌아오는 경로에 따라 인밴드·블라인드·외부 경로로 나뉜다.

## Ⅵ. 실무 사례

1. 로그인 질의에 **매개변수 바인딩 적용**

### 쉽게 이해하기 (학습용)

- 사용자 입력을 SQL 문자열에 이어 붙이지 않고 준비된 문장의 값으로 전달해 입력이 명령 구문으로 실행되지 않게 한다.

## Ⅶ. 결론

- 입력이 SQL 명령으로 해석되는 위험을 제거하기 위해 동적 구문·바인딩 가능성·DB 계정 권한·잔여 공격면을 검토하여, 매개변수 바인딩과 최소 권한을 적용해야 한다.

### 쉽게 이해하기 (학습용)

- SQL 구조와 값을 분리하고 DB 최소 권한으로 피해 범위를 줄인다.
