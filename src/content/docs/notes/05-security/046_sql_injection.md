## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **구조화 질의 언어(Structured Query Language, SQL) 인젝션**: 외부 입력이 명령 구조로 해석돼 질의 의미를 바꾸는 취약점이다.

</details>

- 정의/개념: **SQL 인젝션**은 비신뢰 입력이 질의의 명령 구조로 해석되는 주입 취약점이다.
- 배경/필요성: 문자열 결합 방식은 SQL 구조와 입력값의 경계를 보장할 수 없다.

#### 한줄 요약

- 입력을 값이 아닌 SQL 구문으로 해석하면 질의와 권한이 공격자에게 바뀐다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **준비된 질의**: SQL 구조를 먼저 고정하고 외부 입력을 별도 매개변수 값으로 전달하는 질의 방식이다.
- **값 바인딩**: 외부 입력을 SQL 구문이 아닌 매개변수 값으로 결합하는 처리 방식이다.
- **응답 기반 추론**: 반환 결과의 차이로 질의의 참•거짓과 값을 알아내는 공격 방식이다.
- **오류 기반 추론**: DB 오류 메시지의 차이로 내부 정보와 값을 알아내는 공격 방식이다.
- **시간차 기반 추론**: 응답 지연의 차이로 질의의 참•거짓과 값을 알아내는 공격 방식이다.
- **웹 애플리케이션 방화벽(Web Application Firewall, WAF)**: 웹 요청의 알려진 공격 패턴을 차단하는 보조 통제이다.

</details>

- 문자열 결합 입력은 명령과 값의 구문 경계를 변조하게 만든다.
- **응답 기반 추론**•**오류 기반 추론**•**시간차 기반 추론**으로 직접 보이지 않는 데이터도 알아낼 수 있다.
- **준비된 질의**와 **값 바인딩**으로 주입을 예방하고 **WAF**는 알려진 패턴을 보조 차단한다.

#### 한줄 요약

- 값 바인딩은 구조를 고정하며 WAF와 이스케이프는 보조 통제이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **최소 권한 DB 계정**: 응용에 필요한 스키마•연산만 허용해 주입 성공 때의 피해 범위를 제한하는 계정이다.
- **데이터베이스(Database, DB)**: 응용 데이터를 저장•질의하며 주입된 명령이 실행되는 대상이다.
- **허용목록**: 바인딩할 수 없는 테이블•열 같은 동적 식별자를 승인된 값으로 제한하는 목록이다.

</details>

```text
SQL 실행 경계
├─ 비신뢰 입력: 외부 값 유입
├─ 질의 생성: SQL 구조•입력값 분리
├─ DB 드라이버: 매개변수 값 바인딩
├─ DB 계정: 허용 스키마•연산 제한
└─ 오류•감사: 이상 질의 추적•오류 차단
```

| 구성요소 | 책임 |
|:---|:---|
| 비신뢰 입력 | 폼•API•저장 데이터에서 외부 값 유입 |
| 질의 생성 | 입력값과 **DB**에 전달할 SQL 구조 분리 |
| DB 드라이버 | **값 바인딩**으로 입력 경계 고정 |
| DB 계정 | **최소 권한 DB 계정**으로 피해 범위 제한 |
| 오류•감사 | 이상 질의 추적•오류 노출 차단 |

#### 한줄 요약

- 준비된 질의와 최소 권한이 주입 가능성과 피해 범위를 각각 줄인다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **구조•값 분리**: SQL 명령 형식과 외부 입력을 서로 다른 채널로 DB 드라이버에 전달하는 원칙이다.
- **준비된 SQL 구조 생성**: 실행할 명령 형식과 매개변수 위치를 먼저 고정하는 단계이다.
- **입력값 바인딩**: 외부 입력을 명령이 아닌 매개변수 값으로 전달하는 단계이다.
- **SQL 구조 컴파일•값 처리**: 고정한 질의 구조를 컴파일하고 입력을 값으로만 해석하는 단계이다.
- **최소 권한 질의 실행**: 허용된 스키마와 연산 범위에서 질의를 처리하는 단계이다.
- **질의•오류 감사 기록**: 이상 질의와 오류 노출 여부를 추적 가능한 증거로 남기는 단계이다.

</details>

```text
외부 입력
    |
    v
1. 준비된 SQL 구조 생성
    |
    v
2. 입력값 바인딩
    |
    v
3. SQL 구조 컴파일•값 처리
    |
    v
4. 최소 권한 질의 실행
    |
    v
5. 질의•오류 감사 기록
    |
    v
제한된 질의 결과
```

### 동작 원리

1. **준비된 SQL 구조 생성**: 실행할 명령 형식과 매개변수 위치를 고정해 준비된 SQL 구조 생성을 완료한다.
2. **입력값 바인딩**: 외부 입력을 명령이 아닌 매개변수 값으로 전달해 입력값 바인딩을 수행한다.
3. **SQL 구조 컴파일•값 처리**: 입력을 명령이 아닌 매개변수로 해석해 SQL 구조 컴파일•값 처리를 분리한다.
4. **최소 권한 질의 실행**: 허용 스키마•연산 범위에서만 처리해 최소 권한 질의 실행을 보장한다.
5. **질의•오류 감사 기록**: 이상 질의와 오류 노출 여부를 남겨 질의•오류 감사 기록을 검증 자료로 제공한다.

#### 한줄 요약

- 입력부터 실행점까지 추적해 **구조•값 분리**를 지키고 식별자는 허용목록으로 제한한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **인밴드**: 원래 응답 경로에서 공격 결과를 직접 얻는 방식이다.
- **블라인드**: 참•거짓이나 시간차를 관찰해 결과를 추론하는 방식이다.
- **아웃오브밴드**: 원래 응답과 다른 외부 통신으로 결과를 얻는 방식이다.
- **도메인 이름 시스템(Domain Name System, DNS) 외부 경로**: DB 이름 질의로 정보를 유출하는 경로이다.
- **하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol, HTTP) 외부 경로**: DB 웹 요청으로 정보를 유출하는 경로이다.

</details>

| SQL 인젝션 유형 | 인밴드 | 블라인드 | 아웃오브밴드 |
|:---|:---|:---|:---|
| 적용 기준 | 결과가 직접 노출될 때 | 응답 차이를 관찰할 수 있을 때 | 외부 통신이 가능할 때 |
| 핵심 특징 | 동일 응답 결과 노출 | 응답 차이로 결과 추론 | **DNS 외부 경로**•**HTTP 외부 경로** 같은 별도 통신 경로 유출 |
| 한계 | 대량 데이터 즉시 유출 | 느리지만 응답만으로 추론 | 내부 DB에 별도 외부 통신 경로 필요 |

#### 한줄 요약

- 결과가 돌아오는 경로에 따라 **인밴드**•**블라인드**•**아웃오브밴드**로 나뉜다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **MITRE CWE-89**: 입력값 검토 및 특수 문자 필터링 누락으로 발생하는 SQL 인젝션 약점을 정의한 공통 약점 분류이다.
- **개방형 웹 애플리케이션 보안 프로젝트(Open Worldwide Application Security Project, OWASP)**: 애플리케이션 보안 지침을 공개하는 비영리 프로젝트이다.
- **애플리케이션 보안 검증 표준(Application Security Verification Standard, ASVS) 5.0.0**: 인젝션 방지 요구사항을 제시하는 검증 표준판이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SQL 구조와 입력을 결합하면 명령 경계 변조 | **MITRE CWE-89** 기준으로 문자열 결합 제거 | 입력의 명령 구조 변조 차단 |
| 입력 처리 요구가 없으면 구현별 방어 편차 | **OWASP ASVS 5.0.0** 적용 | 개발•검증의 요구 일관성 확보 |
| 동적 식별자는 값 바인딩이 안 되고 과도한 DB 권한은 피해 확대 | **허용목록**과 **최소 권한 DB 계정** 적용 | 식별자 주입 가능성과 침해 영향 제한 |

#### 한줄 요약

- 사용자 입력을 SQL 문자열에 이어 붙이지 않고 준비된 문장의 값으로 전달해 입력이 명령 구문으로 실행되지 않게 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **SQL 인젝션 통제 선택 기준**: 값에는 준비된 질의와 바인딩, 동적 식별자에는 허용목록, DB 계정에는 최소 권한을 적용하는 판단 기준이다.

</details>

- **SQL 인젝션 통제 선택 기준**에 따라 값은 **준비된 질의**로 **값 바인딩**하고, 식별자는 **허용목록**, DB 계정은 **최소 권한 DB 계정**을 적용한다.

#### 한줄 요약

- SQL 구조와 값을 분리하고 DB 최소 권한으로 피해 범위를 줄인다.
