## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **해시 함수(Hash Function)**: 임의 길이의 데이터를 고정된 길이의 다이제스트로 변환하는 단방향 암호학적 기법.
- **다이제스트(Digest)**: 해시 함수를 통해 임의 메시지에서 도출된 고정 길이 출력값.
- **전송•검증 비용 증가(Transmission & Verification Cost Overhead)**: 원문 데이터 전체를 보관 및 검증함에 따른 연산 및 트래픽 부하.

</details>

- 정의/개념: 임의 길이 메시지를 고정 길이의 고유값으로 단방향 변환하는 **해시 함수** 기법
- 배경/필요성: 원문 전체 저장 및 직접 대조 방식의 **전송•검증 비용 증가** 및 처리 한계 극복

#### 한줄 요약

- 긴 문서에서 짧은 지문을 만들면 두 문서가 같은지 빠르게 비교할 수 있지만, 지문만 보고 원문이나 진짜 작성자를 확인할 수는 없다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **쇄도 효과(Avalanche Effect)**: 입력 데이터의 단 1비트 변경으로도 해시 다이제스트 전체가 완전히 달라지는 특성.
- **역상 저항성(Pre-image Resistance)**: 주어진 해시값 $h$로부터 원본 메시지 $m$을 역계산하는 것이 수학적으로 불가능한 특성.
- **제2역상 저항성(Second Pre-image Resistance)**: 메시지 $m_1$과 동일한 해시값을 출력하는 다른 메시지 $m_2$를 찾을 수 없는 특성.
- **충돌 저항성(Collision Resistance)**: 동일한 해시값을 생성하는 임의의 두 메시지 $(m_1, m_2)$ 쌍을 찾는 것이 불가능한 성질.
- **송신자 인증 불가(Lack of Sender Authentication)**: 비밀키가 없어 누구나 동일 해시 생성이 가능하므로 메시지 작성자 증명이 불가함.

</details>

- 입력의 미세 변화가 출력 전체를 크게 변경하는 **쇄도 효과**
- **역상 저항성**, **제2역상 저항성**, **충돌 저항성**을 통한 위변조 차단
- 키 비동반에 따른 **송신자 인증 불가** 한계 존재

#### 한줄 요약

- 공격자가 파일과 해시값을 함께 바꾸면 계산 결과가 일치하므로, 정상 해시값은 서명이나 신뢰 경로로 따로 보호해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **입력 전처리(Input Preprocessing)**: 메시지 인코딩, 길이 정보 추가, 블록 단위 패딩을 수행하는 초기화 절차.
- **상태 변환 함수(State Compression Function)**: 메시지 블록과 이전 내부 상태를 조합하여 차기 내부 상태를 도출하는 함수.
- **내부 상태(Internal State)**: 각 블록 변환 연산의 결과를 연쇄적으로 축적 및 유지하는 변수값.
- **다이제스트 출력(Digest Finalization)**: 모든 메시지 블록 처리 완료 후 최종 내부 상태를 규격화된 해시값으로 반환하는 연산.

</details>

```text
해시 함수 구조
├─ 입력 전처리
├─ 상태 변환 함수
├─ 내부 상태
└─ 다이제스트 출력
```

가지의 의미: 입력 규격화, 압축 연산, 상태 관리, 최종 출력 책임을 분리한 구조

| 구성요소 | 책임 |
|:---|:---|
| 입력 전처리 | **입력 전처리**가 입력 인코딩•길이 맞춤•블록 분할 수행 |
| 상태 변환 함수 | **상태 변환 함수**가 메시지 블록으로 내부 상태 갱신 |
| 내부 상태 | **내부 상태**가 블록별 계산 결과를 연쇄 유지 |
| 다이제스트 출력 | **다이제스트 출력**이 최종 상태를 고정 길이로 반환 |


#### 한줄 요약

- 입력을 작은 조각으로 나눠 이전 계산 결과에 계속 섞고, 마지막 내부 상태에서 고정 길이 지문을 꺼낸다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **패딩(Padding)**: 입력 메시지를 블록 크기 배수에 맞추고 원래 메시지 길이를 합산 덧붙이는 전처리.
- **반복 상태 갱신(Iterative State Update)**: 순차 분할된 블록들을 이전 해시 상태와 연계하여 반복 압축하는 과정.
- **인코딩•패딩(Encoding & Padding Stage)**: 데이터를 정해진 포맷으로 변환하고 고정 블록 크기로 패딩을 덧붙이는 과정.
- **메시지 블록 전달(Message Block Delivery)**: 패딩 처리된 메시지 블록을 상태 변환 모듈에 순차 전달하는 단계.
- **내부 상태 갱신(Internal State Compression)**: 압축 함수를 호출하여 메시지 블록별 내부 상태를 지속 갱신하는 단계.
- **다이제스트 생성(Digest Generation Stage)**: 최종 단계의 내부 상태로부터 지정된 길이의 해시값을 추출하는 절차.

</details>

```text
메시지 입력
        │
        ▼
1. 인코딩•패딩
        │
        ▼
2. 메시지 블록 전달
        │
        ▼
3. 내부 상태 갱신
        └── 모든 블록 처리까지 반복
                    │
                    ▼
4. 다이제스트 생성
        │
        └── 해시값 반환
```

### 동작 원리

1. **인코딩•패딩**: 메시지 길이 정보를 포함한 **인코딩•패딩** 적용
2. **메시지 블록 전달**: 고정 규격 블록 단위의 **메시지 블록 전달** 수행
3. **내부 상태 갱신**: 압축 함수 연산을 통한 **내부 상태 갱신** 반복
4. **다이제스트 생성**: 최종 변환 상태 기반의 **다이제스트 생성** 및 반환


#### 한줄 요약

- 입력을 같은 규칙으로 나누고 모든 블록을 내부 상태에 차례로 섞어 고정 길이 지문을 만든다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **SHA-2(Secure Hash Algorithm 2)**: SHA-256, SHA-512 등을 포함하는 대표적 암호학적 해시 표준 알고리즘.
- **SHA-3(Secure Hash Algorithm 3)**: 스펀지(Sponge) 구조를 채택하여 기존 SHA-2와 내부 아키텍처를 달리한 해시 표준.
- **SHA-1(Secure Hash Algorithm 1)**: 160비트 출력 크기를 가지나 실용적 충돌 공격 가능성으로 사용이 취약해진 구형 알고리즘.
- **FIPS 180-4(FIPS 180-4 Standard)**: SHA-1, SHA-2 계열의 해시 알고리즘 규격을 명시한 미국 정부 표준.
- **FIPS 202(FIPS 202 Standard)**: Keccak 기반 SHA-3 해시 함수 계열을 정의한 NIST 표준 문서.

</details>

| 해시 알고리즘 | **SHA-2** | **SHA-3** | **SHA-1** |
|:---|:---|:---|:---|
| 적용 기준 | 서명•HMAC•파일 무결성 | 다른 내부 구조가 필요한 설계 | 기존 식별값 호환 검증만 |
| 핵심 특징 | **FIPS 180-4** 규격 | **FIPS 202** 스펀지 구조 | 160비트 구형 해시 |
| 한계 | 입력 규칙 불일치 시 검증 실패 | 구현•프로토콜 지원 확인 | 충돌 공격으로 보안 적용 부적합 |

> 요약: 보편적 표준 SHA-2, 구조 다변화 대안 SHA-3 중심 적용

#### 한줄 요약

- SHA-1은 숫자가 길어 보여도 같은 지문을 가진 두 문서를 만들 수 있으므로 새 보안 설계에서 제외하고, 호환성과 구조 요구에 따라 SHA-2나 SHA-3를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **솔트(Salt)**: 레인보우 테이블 공격 및 동일 패스워드 추측을 방지하기 위해 추가하는 솔트 난수값.
- **Argon2id(Argon2id Key Derivation)**: 메모리 집약적 연산을 통해 GPU 전수조사 및 부채널 공격을 방어하는 패스워드 전용 해시 함수.
- **HMAC(Hash-based Message Authentication Code)**: 해시 함수와 대칭키를 조합하여 메시지 무결성과 송신자 인증을 동시에 보장함.
- **입력 정규화(Input Normalization)**: 데이터 이종 환경에서 동일 해시값 재현을 위한 텍스트/데이터 표준화 포맷 지정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기준 해시값의 동시 변조 | **HMAC**•서명•신뢰 저장소 보호 | 비교 기준 신뢰성 확보 |
| 입력 정규화 규칙 불일치 | **입력 정규화** 명시•시험 | 재현 가능한 검증 |
| SHA-1 충돌 위험 | FIPS 180-4•202 전환 | **충돌 저항성** 확보 |
| 비밀번호의 고속 전수조사 | **솔트**•**Argon2id** 적용 | 메모리 경화로 공격 비용 증가 |

#### 한줄 요약

- 기준값은 서명된 신뢰 경로에 보관하고 같은 입력 규칙과 승인된 SHA-2•SHA-3로 다시 계산해야 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **용도 분리(Application Context Separation)**: 무결성/디지털서명용 해시와 패스워드 저장용 메모리 경화 해시의 목적별 명확한 통제 적용.

</details>

- 메시지 무결성 및 서명은 **SHA-2**, 패스워드 저장은 **Argon2id**를 선택하는 **용도 분리** 방침 수립

#### 한줄 요약

- 해시값이 같다는 사실만 보지 말고, 충돌 공격에 안전한 알고리즘인지와 비교한 기준값이 신뢰 경로에서 왔는지를 함께 확인해야 한다.
