## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **암호학적 해시 함수(Cryptographic Hash Function)**: 임의의 가변 길이(Variable-Length) 바이너리 메시지를 입력받아, 수학적 단방향 압축 연산을 통해 항상 고정된 길이(Fixed-Length)의 고유한 비트열(메시지 다이제스트 / 해시값)을 출력하는 알고리즘.
- **메시지 다이제스트(Message Digest)**: 원본 데이터의 암호학적 디지털 지문(Fingerprint) 역할을 수행하는 고정 크기(예: SHA-256 기준 256비트)의 결과값.

</details>

- 정의/개념: 데이터의 단 1비트 변경도 출력 전체의 비선형적 무작위 변화를 유발하는 **쇄도 효과(Avalanche Effect)** 와 **3대 저항성(제1역상, 제2역상, 충돌 저항성)** 을 바탕으로 데이터의 무결성(Integrity)과 암호학적 신뢰성을 검증하는 **단방향 암호 기술**
- 배경/필요성: 대용량 파일 및 네트워크 트래픽 전체를 매번 원문 대조하는 통신·연산 비효율을 해결하고, 전자서명, 블록체인 블록 연계, 패스워드 안전 저장의 고정 크기 지문 생성 메커니즘을 확립할 요구

#### 한줄 요약
- 임의 길이 데이터를 고정 길이 다이제스트로 변환하여 3대 저항성을 통해 무결성을 수학적으로 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **3대 암호학적 저항성**:
  1. **제1역상 저항성(Pre-image Resistance)**: 주어진 해시값 $h$로부터 $h = H(m)$을 만족하는 원본 메시지 $m$을 계산하는 것이 불가능한 단방향성.
  2. **제2역상 저항성(Second Pre-image Resistance / 약한 충돌 저항성)**: 특정 메시지 $m_1$이 주어졌을 때, $H(m_1) = H(m_2)$를 만족하는 다른 메시지 $m_2$를 찾는 것이 불가능한 성질.
  3. **충돌 저항성(Collision Resistance / 강한 충돌 저항성)**: 동일한 해시값을 갖는 임의의 서로 다른 두 메시지 쌍 $(m_1, m_2)$ ($m_1 \neq m_2$)을 찾아내는 것이 계산적으로 불가능한 성질 (생일 역설 공격 저항).

</details>

- **결정론적 압축 및 쇄도 효과 (Avalanche Effect)**: 동일 입력에 대해 항상 동일한 다이제스트를 생성하되, 입력의 1비트 변경 시 출력 비트의 50% 이상이 무작위 반전
- **수학적 단방향성 (One-Way Property)**: 다이제스트로부터 원본 복원 연산이 계산 복잡도 상 불가능
- **출처 인증의 한계**: 비밀키가 개입되지 않으므로 해시 단독으로는 송신자의 신원 인증(Authentication) 및 부인방지가 불가능하여 HMAC이나 전자서명 결합 필수

#### 한줄 요약
- 결정론적 압축, 쇄도 효과, 3대 저항성(제1/제2역상, 충돌 저항성)을 제공하며 출처 인증을 위해 HMAC과 결합한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **머클-담가드 구조(Merkle-Damgård Construction)**: 메시지를 고정 크기 블록으로 패딩/분할한 후, 압축 함수(Compression Function)를 연쇄적(Chaining)으로 반복 실행하여 최종 다이제스트를 도출하는 SHA-1, SHA-2의 설계 구조.
- **스펀지 구조(Sponge Construction)**: SHA-3(Keccak)에서 채택된 구조로, 입력 메시지를 상태 배열로 흡수(Absorb)한 후 치환 순열(Keccak-f)을 거쳐 원하는 길이의 출력을 짜내는(Squeeze) 차세대 해시 구조.

</details>

```text
[ 임의 길이 입력 메시지 (Variable-Length Message) ]
                      │
                      ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 입력 전처리 및 패딩 (Padding: Message Length + '100...0' 비트 주입) ] │
│  └─ 메시지를 $N$개의 512비트 블록으로 완전 정렬: ($M_1, M_2, \dots, M_N$)│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 머클-담가드 연쇄 압축 함수 (Compression Function Loop) ]            │
│     IV (초기화 벡터) ──▶ [ 압축 함수 $f$ ] ──▶ $H_1$                      │
│                           ▲                                             │
│                           │ $M_1$ 블록 주입                             │
│                           └──────────────────▶ [ 압축 함수 $f$ ] ──▶ $H_N$│
│                                                 ▲                       │
│                                                 │ $M_N$ 블록 주입       │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
                  [ 3. 고정 길이 다이제스트 (256비트 $H_N$) 출력 ]
```

선의 의미: 입력 메시지가 패딩을 거쳐 512비트 블록들로 분할되고, 이전 압축 함수의 결과값이 다음 블록의 입력으로 연쇄 누적되어 최종 다이제스트를 출력하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **입력 패딩 모듈** | 블록 단위(512/1024bit) 정렬을 위해 비트 '1'과 0들을 채우고 원본 길이(64bit) 부착 | RFC 6234 |
| **초기화 벡터 (IV)** | 해시 알고리즘 표준에 정의된 고정된 불변 상수 비트열 (초기 내부 상태 설정) | NIST FIPS 180-4 |
| **압축 함수 ($f$)** | 이전 Chaining Value($H_{i-1}$)와 현재 메시지 블록($M_i$)을 혼합 압축 | Davies-Meyer 구조 |
| **라운드 상수 및 함수** | 논리 연산(AND, OR, XOR), 비트 회전(ROTR, SHR), 덧셈을 통한 비선형 혼돈/확산 | 비선형 라운드 연산 |
| **최종 다이제스트** | 모든 메시지 블록의 압축이 완료된 후 출력되는 최종 고정 해시값 | 256/384/512 bits |

#### 한줄 요약
- 패딩 모듈, 초기화 벡터(IV), 압축 함수, 라운드 비선형 함수, 최종 다이제스트가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **길이 연장 공격(Length Extension Attack)**: 머클-담가드 구조의 해시 함수($H$)에서 비밀키와 메시지의 결합 $H(\text{Secret} \parallel M)$을 사용할 때, 공격자가 Secret을 몰라도 기존 해시값 $H$와 메시지 길이만으로 $H(\text{Secret} \parallel M \parallel M_{\text{evil}})$의 유효한 해시값을 위조할 수 있는 취약점.

</details>

```text
1. 임의 길이의 원본 데이터 인입 ➔ 512비트 배수가 되도록 패딩(Padding) 및 64비트 길이 정보 추가
            │
            ▼
2. 8개의 32비트 워드로 구성된 표준 초기 상태 레지스터($A, B, C, D, E, F, G, H$)를 IV 상수로 로드
            │
            ▼
3. 512비트 메시지 블록을 64개의 32비트 메시지 스케줄 워드($W_0 \sim W_{63}$)로 확장
            │
            ▼
4. 64 라운드 동안 비선형 논리 함수($Ch, Maj, \Sigma_0, \Sigma_1$) 및 비트 시프트를 적용하여 레지스터 상태 갱신
            │
            ▼
5. 최종 블록 처리 후 8개 레지스터 값을 연결(Concatenation)하여 256비트 메시지 다이제스트 반환
```

**동작 원리**

1. **메시지 정렬**: $M \equiv 448 \pmod{512}$가 되도록 비트 '1'과 '0'을 채운 후 64비트 길이 덧붙임
2. **메시지 확장**: 16개 워드를 순환 이동(Rotate) 및 덧셈을 통해 64개 스케줄 워드로 확산
3. **라운드 혼돈**: 이전 라운드의 중간 변수들을 $T_1 = H + \Sigma_1(E) + Ch(E,F,G) + K_t + W_t$로 연산
4. **연쇄 상태 결합**: 64 라운드 종료 후 초기 레지스터 값과 연산 결과를 덧셈하여 중간 해시값 도출
5. **다이제스트 확정**: 최종 블록까지의 누적 상태를 16진수 문자열로 포맷팅하여 출력

#### 한줄 요약
- 블록 패딩, 워드 스케줄 확장, 64 라운드 비선형 압축, 연쇄 상태 갱신, 고정 다이제스트 출력 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SHA-2 vs SHA-3 vs 레거시 MD5/SHA-1**: 머클-담가드 기반 표준 SHA-2, 스펀지 기반 차세대 SHA-3, 충돌쌍 발견으로 폐기된 레거시 알고리즘 비교.

</details>

| 알고리즘 | 내부 구조 | 출력 다이제스트 크기 | 충돌 저항성 안전성 | 길이 연장 공격 취약성 | 주요 상태 및 권고 |
|:---|:---|:---|:---|:---|:---|
| **MD5** | Merkle-Damgård | 128 bits | **완전 붕괴 (수초 내 충돌 생성)**| 취약 | **사용 절대 금지 (폐기)** |
| **SHA-1** | Merkle-Damgård | 160 bits | **붕괴 (SHAttered 공격 실증)** | 취약 | **사용 절대 금지 (폐기)** |
| **SHA-2 (SHA-256/512)**| Merkle-Damgård | **256 / 512 bits** | **현재 완전 안전 (충돌 전무)** | **취약 (HMAC 결합 필수)** | **현재 글로벌 표준 (NIST FIPS 180-4)** |
| **SHA-3 (Keccak)** | **Sponge 구조** | **224 / 256 / 384 / 512** | **현재 완전 안전 (수학적 격리)**| **구조적으로 면역 (안전)** | **차세대 표준 (NIST FIPS 202)** |

#### 한줄 요약
- MD5/SHA-1은 충돌 발생으로 폐기되었으며, SHA-2는 현재 사실상 표준이고, SHA-3는 길이 연장 공격에 면역인 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **레인보우 테이블(Rainbow Table)**: 미리 계산된 수십억 개의 평문-해시값 쌍을 역함수(Reduction Function) 체인으로 압축 저장하여, 솔트가 적용되지 않은 해시값을 수 밀리초 만에 역산하는 오프라인 크래킹 테이블.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단순 해시된 패스워드가 GPU 병렬 연산 및 **레인보우 테이블 공격으로 실시간 역산 노출** | **사용자별 고유 솔트(Salt $\ge 128\text{bit}$) 적용 및 메모리 경화 해시(Argon2id/bcrypt)** 강제 | 레인보우 테이블 무력화 및 GPU/ASIC 무차별 대입 크래킹 비용 극대화 |
| 머클-담가드 해시(SHA-256)의 단순 결합 $H(K \parallel M)$ 사용 시 **길이 연장 공격으로 메시지 위조** | **표준 HMAC(RFC 2104: $H((K \oplus opad) \parallel H((K \oplus ipad) \parallel M))$) 또는 SHA-3** 사용 | 해시 내부 상태 확장 차단 및 메시지 무결성/인증 100% 보증 |
| 개행 문자(CRLF/LF) 및 인코딩(UTF-8/EUC-KR) 차이로 인한 **무결성 검증 실패(오탐/미탐)** | 해시 계산 전 입력 데이터에 대한 **정규화(Canonicalization / C14N) 파이프라인** 선행 | 포맷 차이로 인한 쇄도 효과 오작동 제거 및 일관된 무결성 검증 보장 |

#### 한줄 요약
- Argon2id/Salt로 레인보우 테이블을 막고, HMAC으로 길이 연장 공격을 차단하며, 정규화로 검증 오류를 방지한다.

## Ⅶ. 결론

- 디지털 정보의 무결성과 진본성을 수학적으로 증명하는 **암호학적 해시 알고리즘**은 전자서명, 블록체인, 인증 프로토콜의 핵심 토대이며, 실무 구현 시 **충돌 취약 알고리즘(MD5, SHA-1)의 전면 폐기**, **SHA-2 및 SHA-3 표준 채택**, **데이터 인증 시 HMAC 결합**, **패스워드 저장 시 Argon2id/PBKDF2 메모리 경화 함수 적용**을 준수하여 완결성 높은 데이터 무결성 인프라를 완성

#### 한줄 요약
- 3대 저항성을 갖춘 SHA-2/SHA-3와 HMAC 및 Argon2id를 용도별로 엄격히 분리 적용하여 안전한 무결성을 실현한다.
