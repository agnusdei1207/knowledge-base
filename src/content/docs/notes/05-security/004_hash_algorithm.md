## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Cryptographic Hash Function (암호학적 해시 함수)**: 임의 길이의 데이터를 고정 길이의 메시지 다이제스트로 단방향 변환하는 수학적 알고리즘.
- **Avalanche Effect (쇄도 효과)**: 입력 데이터의 단 1비트만 변경되어도 출력 해시값의 50% 이상이 무작위로 뒤바뀌는 암호학적 특성.

</details>

- 정의/개념: 임의 입력을 고정 길이로 매핑하는 **단방향 해시 함수**
- 배경/필요성: 소프트웨어 배포 파일, 디지털 거래 데이터 및 블록체인의 무결성을 검증할 때, 원본 전체를 보관/대조하는 방식은 막대한 스토리지 및 네트워크 대역폭 낭비를 초래하고 단순 체크섬(CRC32/MD5) 방식은 공격자가 악성 코드를 삽입하면서도 동일한 검사합을 의도적으로 위조해낼 수 있는 충돌 취약점을 드러냄에 따라, 임의 길이의 데이터를 고정 길이의 메시지 다이제스트로 일방향 변환하며 3대 보안 저항성(제1역상, 제2역상, 충돌 저항성)과 쇄도 효과(Avalanche Effect)를 보장하는 암호학적 해시 알고리즘(SHA-2/SHA-3)을 도입하여 **원본 데이터의 위변조 여부를 O(1) 수준으로 즉각 검증하는 무결성(Integrity) 보장, 전자서명 및 블록체인 머클 트리(Merkle Tree)의 암호학적 지문(Fingerprint) 역할**을 달성할 필요

#### 한줄 요약
- 단방향 압축과 3대 저항성을 통해 데이터의 위변조 여부를 고속으로 무결성 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Preimage Resistance (제1역상 저항성)**: 주어진 해시값 $h$로부터 $h=H(m)$을 만족하는 원본 메시지 $m$을 찾는 것이 불가능함 ($O(2^n)$).
- **Collision Resistance (충돌 저항성)**: $H(m_1) = H(m_2)$를 만족하는 서로 다른 두 메시지 $m_1, m_2$ 쌍을 찾는 것이 불가능함 ($O(2^{n/2})$).

</details>

- 해시값에서 입력 탐색을 어렵게 하는 **제1역상 저항성**
- 지정 입력의 대체 입력 탐색을 막는 **제2역상 저항성**
- 서로 다른 입력 쌍 탐색을 막는 **충돌 저항성**

#### 한줄 요약
- 임의 길이를 고정 길이로 압축하는 순간 충돌은 수학적으로 불가피하므로, 세 저항성은 충돌을 없애는 것이 아니라 찾는 비용을 $2^{n/2}$ 이상으로 밀어 올리는 경제적 방어다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Merkle-Damgård Construction**: 메시지를 고정 블록으로 패딩/분할한 후 초기 벡터(IV)와 함께 압축 함수($f$)를 연쇄 적용하는 고전 해시 구조.

</details>

```text
SHA-256
|-- Padding Module
|-- Initialization Vector
|-- Compression Function
|-- Round Function
`-- Digest
```

선의 의미: 입력 메시지가 패딩을 거쳐 512비트 블록으로 분할되고 이전 압축 함수의 결과값이 다음 블록의 입력으로 연쇄 누적되는 구조

| 구성요소 | 책임 |
|:---|:---|
| **Padding Module** | 블록 정렬과 원본 길이 부착 |
| **Initialization Vector** | 최초 체이닝 상태 제공 |
| **Compression Function** | 상태와 메시지 블록 혼합 |
| **Round Function** | Ch·Maj·회전 기반 상태 갱신 |
| **Digest** | 최종 고정 길이 해시 출력 |

#### 한줄 요약
- 압축 함수를 블록마다 연쇄시켜 입력 길이와 무관한 고정 상태만 유지하는 대신, 그 중간 상태가 곧 최종 출력이라는 구조적 대가로 Merkle-Damgård 계열은 길이 연장 공격에 노출된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Length Extension Attack (길이 연장 공격)**: Merkle-Damgård 구조에서 $H(\text{Key} \parallel M)$ 사용 시 Key를 몰라도 해시 상태를 이어받아 메시지를 악의적으로 위조하는 공격.

</details>

```text
SHA-256 패딩, 메시지 확장, 64라운드 압축 및 다이제스트 출력 파이프라인
        │
   1. [패딩 및 길이 추가]
        │
   2. [초기 레지스터 로드]
        │
   3. [메시지 스케줄 확장]
        │
   4. [64라운드 비선형 압축]
        │
   ▼
   5. [최종 다이제스트 출력]
```

- 1. 패딩 및 길이 추가
- 2. 초기 레지스터 로드
- 3. 메시지 스케줄 확장
- 4. 64라운드 비선형 압축
- 5. 최종 다이제스트 출력

#### 한줄 요약
- 라운드 수는 곧 연산 비용이자 안전 여유이므로, 파일 무결성처럼 속도가 중요한 용도와 비밀번호처럼 일부러 느려야 하는 용도가 같은 함수를 공유할 수 없다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MD5 vs SHA-1 vs SHA-2 vs SHA-3**: 폐기된 레거시, 현재 표준(SHA-2), 스펀지 구조의 차세대 표준(SHA-3).

</details>

| 알고리즘 | 내부 구조 | 출력 다이제스트 크기 | 충돌 저항성 안전성 | 길이 연장 공격 취약성 | 주요 상태 및 권고 |
|:---|:---|:---|:---|:---|:---|
| MD5 | Merkle-Damgård | 128 bits | 실용 충돌 공격 존재 | 취약 | 신규 보안 용도 제외 |
| SHA-1 | Merkle-Damgård | 160 bits | 실용 충돌 공격 존재 | 취약 | 신규 보안 용도 제외 |
| SHA-2 | Merkle-Damgård | 256·512 bits | 알려진 실용 충돌 없음 | 취약 | **FIPS 180-4** |
| SHA-3 | Sponge | 224·256·384·512 bits | 알려진 실용 충돌 없음 | 해당 구조 공격 회피 | **FIPS 202** |

#### 한줄 요약
- MD5/SHA-1은 충돌 발생으로 폐기되었으며, SHA-2는 현재 사실상 표준이고, SHA-3는 길이 연장 공격에 면역인 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Rainbow Table Attack**: 미리 계산된 수십억 개의 평문-해시값 쌍을 압축 저장하여 솔트 없는 해시를 수 밀리초 만에 역산하는 오프라인 크래킹.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비밀번호 해시의 **GPU·레인보우 공격** | 사용자별 Salt와 **Argon2id** | 사전 계산 차단·탐색 비용 증가 |
| `H(K || M)`의 **길이 연장 공격** | **HMAC** 또는 SHA-3 사용 | 내부 상태 재사용 방지 |
| 개행 차이로 무결성 오탐 | 입력 **Canonicalization** | 동일 의미의 표현 통일 |
| 단순 파일 해시의 동시 위조 | 해시값 **전자서명 검증** | 해시 출처 인증 |

#### 한줄 요약
- Argon2id/Salt로 레인보우 테이블을 막고, HMAC으로 길이 연장 공격을 차단하며, 정규화로 검증 오류를 방지한다.

## Ⅶ. 결론

- 전자서명, 블록체인, TLS 핸드셰이크 및 소프트웨어 무결성 검증의 암호학적 지문(Fingerprint) 역할을 수행하는 **정보보안 및 암호학의 가장 기본적이면서도 핵심적인 데이터 무결성 검증 표준 기술(FIPS 180-4 / FIPS 202)**로 확고히 자리매김하였으며, 양자 컴퓨터 충돌 공격에 대비한 SHA-384/512 및 스펀지 구조(SHA-3)로 진화하는 가운데, 실무 암호 해시 시스템 설계 시에는 **충돌 취약점이 발견된 MD5 및 SHA-1의 완전 폐기 및 SHA-256/SHA-3 표준화, 단순 결합 $H(K\parallel M)$의 길이 연장 공격(Length Extension Attack)을 방어하는 HMAC(RFC 2104) 적용, GPU 병렬 크래킹 및 레인보우 테이블을 무력화하는 고유 Salt 기반 메모리 하드 비밀번호 KDF(Argon2id / PBKDF2)**를 용도에 맞게 엄격히 분리 적용하여 완벽한 데이터 무결성과 신뢰성을 완성

#### 한줄 요약
- 해시 알고리즘은 3대 저항성을 갖춘 SHA-2/SHA-3와 HMAC 및 Argon2id를 용도별로 분리 적용하여 안전한 데이터 무결성을 보장한다.
