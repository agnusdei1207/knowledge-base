## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Cryptographic Hash Function (암호학적 해시 함수)**: 임의 길이의 데이터를 고정 길이의 메시지 다이제스트로 단방향 변환하는 수학적 알고리즘.
- **Avalanche Effect (쇄도 효과)**: 입력 데이터의 단 1비트만 변경되어도 출력 해시값의 50% 이상이 무작위로 뒤바뀌는 암호학적 특성.

</details>

- 정의/개념: 임의 길이의 데이터를 고정 크기 다이제스트로 변환하여 **3대 저항성(제1·2역상, 충돌)과 쇄도 효과를 통해 무결성을 검증하는 단방향 암호 기술**
- 배경/필요성: 원문 직접 대조 시의 **스토리지/네트워크 대역폭 낭비, 비암호학적 체크섬(CRC32)의 악의적 위변조 탐지 불가**

#### 한줄 요약
- 단방향 압축과 3대 저항성을 통해 데이터의 위변조 여부를 고속으로 무결성 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Preimage Resistance (제1역상 저항성)**: 주어진 해시값 $h$로부터 $h=H(m)$을 만족하는 원본 메시지 $m$을 찾는 것이 불가능함 ($O(2^n)$).
- **Collision Resistance (충돌 저항성)**: $H(m_1) = H(m_2)$를 만족하는 서로 다른 두 메시지 $m_1, m_2$ 쌍을 찾는 것이 불가능함 ($O(2^{n/2})$).

</details>

- **단방향 비가역성(Preimage Resistance)**: 출력된 해시값으로부터 **역산(Reverse Engineering)을 통해 원본 평문 복구 원천 차단**
- **강력한 충돌 저항성(Collision Resistance)**: 생일 역설 공격에도 견디며 **서로 다른 입력이 동일 해시값을 출력할 확률을 $2^{-128}$ 이하로 통제**
- **고정 크기 출력 및 빠른 연산**: 입력 크기와 무관하게 **256/512비트 고정 길이를 생성하여 전자서명 및 블록체인 블록 해시 최적화**

#### 한줄 요약
- 단방향 비가역성, 강력한 충돌 저항성, 고정 크기 고속 출력을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Merkle-Damgård Construction**: 메시지를 고정 블록으로 패딩/분할한 후 초기 벡터(IV)와 함께 압축 함수($f$)를 연쇄 적용하는 고전 해시 구조.

</details>

```text
[SHA-256 머클-담가드 연쇄 압축 아키텍처]
|-- Input Message (임의 길이 원본 데이터)
`-- 1. Padding & Parsing (512비트 블록 정렬: 비트 '1' + 0s + 64bit 길이 정보)
`-- 2. Merkle-Damgard Compression Function Loop
    |-- IV (초기화 벡터 상수 A~H) -> [ 압축 함수 f (M_1 블록 주입) ] -> H_1
    `-- ... -> [ 압축 함수 f (M_N 블록 주입) ] -> H_N
`-- 3. Output Digest (최종 256비트 고정 메시지 다이제스트 H_N 반환)
```

선의 의미: 입력 메시지가 패딩을 거쳐 512비트 블록으로 분할되고 이전 압축 함수의 결과값이 다음 블록의 입력으로 연쇄 누적되는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **입력 패딩 모듈** | 512비트 블록 정렬을 위해 **비트 '1'과 0을 채우고 원본 길이(64bit) 부착** | RFC 6234 |
| **초기화 벡터 (IV)**| 해시 표준에 정의된 **고정된 불변 상수 비트열 (초기 상태 설정)** | NIST FIPS 180-4 |
| **압축 함수 ($f$)** | 이전 Chaining Value와 **현재 메시지 블록을 혼합하여 비선형 압축** | Davies-Meyer |
| **라운드 상수 및 함수**| 논리 연산(Ch, Maj)과 **비트 회전(ROTR)을 통한 비선형 혼돈/확산** | 64 Rounds |
| **최종 다이제스트** | 모든 블록의 압축이 완료된 후 **출력되는 최종 고정 해시값** | 256/512 bits |

#### 한줄 요약
- 패딩 모듈, 초기화 벡터(IV), 압축 함수, 라운드 비선형 함수, 최종 다이제스트가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Length Extension Attack (길이 연장 공격)**: Merkle-Damgård 구조에서 $H(\text{Key} \parallel M)$ 사용 시 Key를 몰라도 해시 상태를 이어받아 메시지를 악의적으로 위조하는 공격.

</details>

```text
SHA-256 패딩, 메시지 확장, 64라운드 압축 및 다이제스트 출력 파이프라인
        │
   1. [패딩 및 길이 추가] 원본 데이터를 512비트 배수가 되도록 비트 '1'과 64비트 길이 정보 추가
        │
   2. [초기 레지스터 로드] 8개의 32비트 상태 레지스터($A \sim H$)에 표준 IV 상수 로드
        │
   3. [메시지 스케줄 확장] 512비트 블록을 64개의 32비트 스케줄 워드($W_0 \sim W_{63}$)로 확산
        │
   4. [64라운드 비선형 압축] $Ch, Maj, \Sigma_0, \Sigma_1$ 논리 함수 및 비트 시프트로 상태 레지스터 갱신
        │
   ▼
5. [최종 다이제스트 출력] 최종 블록 연산 후 8개 레지스터를 연결하여 256비트 해시값 반환
```

#### 한줄 요약
- 블록 패딩 → 워드 스케줄 확장 → 64 라운드 비선형 압축 → 연쇄 상태 갱신 → 고정 다이제스트 출력 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **MD5 vs SHA-1 vs SHA-2 vs SHA-3**: 폐기된 레거시, 현재 표준(SHA-2), 스펀지 구조의 차세대 표준(SHA-3).

</details>

| 알고리즘 | 내부 구조 | 출력 다이제스트 크기 | 충돌 저항성 안전성 | 길이 연장 공격 취약성 | 주요 상태 및 권고 |
|:---|:---|:---|:---|:---|:---|
| **MD5** | Merkle-Damgård | 128 bits | **완전 붕괴 (수초 내 충돌 생성)**| 취약 | **사용 절대 금지 (폐기)** |
| **SHA-1** | Merkle-Damgård | 160 bits | **붕괴 (SHAttered 공격 실증)** | 취약 | **사용 절대 금지 (폐기)** |
| **SHA-2 (SHA-256/512)**| Merkle-Damgård | **256 / 512 bits** | **현재 완전 안전 (충돌 전무)** | **취약 (HMAC 결합 필수)** | **현재 글로벌 표준 (NIST FIPS 180-4)** |
| **SHA-3 (Keccak)** | **Sponge 구조** | **224 / 256 / 384 / 512** | **현재 완전 안전 (수학적 격리)**| **구조적으로 면역 (안전)** | **차세대 표준 (NIST FIPS 202)** |

#### 한줄 요약
- MD5/SHA-1은 충돌 발생으로 폐기되었으며, SHA-2는 현재 사실상 표준이고, SHA-3는 길이 연장 공격에 면역인 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Rainbow Table Attack**: 미리 계산된 수십억 개의 평문-해시값 쌍을 압축 저장하여 솔트 없는 해시를 수 밀리초 만에 역산하는 오프라인 크래킹.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단순 해시된 비밀번호의 **GPU 병렬 연산 및 레인보우 테이블 크래킹 노출** | **`사용자별 솔트(Salt >= 128bit)` 및 `메모리 경화 해시(Argon2id/bcrypt)`** 강제 | 레인보우 테이블 무력화 및 무차별 대입 비용 극대화 |
| 머클-담가드 해시($H(K \parallel M)$) 사용 시 **길이 연장 공격으로 메시지 위조** | **표준 HMAC(RFC 2104: `$H((K \oplus opad) \parallel H((K \oplus ipad) \parallel M))$`) 또는 SHA-3** 사용 | 해시 내부 상태 확장 차단 및 메시지 무결성 보증 |
| 개행 문자(CRLF/LF) 차이로 인한 **무결성 검증 실패(오탐)** | 해시 계산 전 입력 데이터에 대한 **`정규화(Canonicalization / C14N)`** 선행 | 포맷 차이로 인한 쇄도 효과 오작동 제거 |
| 파일 다운로드 위변조 탐지를 위한 단순 해시 검증의 위조 위험 | **해시값 자체에 대한 `공개키 전자서명 검증 체계` 병행** | 중간자 공격자의 해시값 동시 변조 원천 차단 |

#### 한줄 요약
- Argon2id/Salt로 레인보우 테이블을 막고, HMAC으로 길이 연장 공격을 차단하며, 정규화로 검증 오류를 방지한다.

## Ⅶ. 결론

- 디지털 정보의 무결성과 진본성을 수학적으로 증명하는 **암호학적 해시 알고리즘은 전자서명, 블록체인, 인증 프로토콜의 핵심 토대**이며, 실무 구현 시 **충돌 취약 알고리즘(MD5, SHA-1)의 전면 폐기, SHA-2 및 SHA-3 표준 채택, 데이터 인증 시 HMAC 결합, 패스워드 저장 시 Argon2id 메모리 경화 함수 적용**을 준수하여 완결성 높은 데이터 무결성 인프라 완성

#### 한줄 요약
- 해시 알고리즘은 3대 저항성을 갖춘 SHA-2/SHA-3와 HMAC 및 Argon2id를 용도별로 분리 적용하여 안전한 데이터 무결성을 보장한다.
