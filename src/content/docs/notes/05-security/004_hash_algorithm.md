## 미리 알고가기

- **해시 알고리즘(Hash Algorithm)**: 길이가 다른 입력을 고정 길이 값으로 압축해 변경 탐지와 서명 입력 등에 사용하는 단방향 함수
- **다이제스트(Digest)**: 해시 함수가 입력 전체를 계산해 만든 고정 길이 출력값
- **역상 저항성(Preimage Resistance)**: 주어진 해시값과 일치하는 원문을 찾기 어려운 성질
- **제2역상 저항성(Second-preimage Resistance)**: 주어진 원문과 같은 해시값을 만드는 다른 원문을 찾기 어려운 성질
- **충돌 저항성(Collision Resistance)**: 같은 해시값을 만드는 서로 다른 두 입력을 찾기 어려운 성질
- **쇄도 효과(Avalanche Effect)**: 입력 한 비트만 달라져도 출력 비트가 전반적으로 달라지는 성질
- **솔트(Salt)**: 같은 비밀번호도 서로 다른 저장값이 되도록 비밀번호마다 추가하는 임의값
- **메시지 인증 코드(Message Authentication Code, MAC)**: 비밀키를 이용하여 메시지의 무결성과 송신자 정당성을 검증하는 인증값
- **해시 기반 메시지 인증 코드(Hash-based Message Authentication Code, HMAC)**: 해시 함수와 비밀키를 결합하여 메시지 인증 코드를 생성하는 방식
- **보안 해시 알고리즘 1(Secure Hash Algorithm 1, SHA-1)**: 충돌 공격이 실용화되어 새로운 보안 설계에서는 사용하지 않는 해시 알고리즘
- **보안 해시 알고리즘 2(Secure Hash Algorithm 2, SHA-2)**: SHA-256·SHA-512 등을 포함하며 전자서명과 데이터 무결성 검증에 사용하는 해시 알고리즘군
- **보안 해시 알고리즘 3(Secure Hash Algorithm 3, SHA-3)**: 스펀지 구조로 입력을 흡수하고 해시값을 출력하는 해시 알고리즘
- **SHA-256·SHA-512**: 각각 256비트와 512비트 해시값을 생성하는 SHA-2 계열 알고리즘
- **아르곤2아이디(Argon2id)**: 데이터 의존 방식과 주소 의존 방식을 결합하여 부채널·GPU 공격에 대응하는 메모리 경화 비밀번호 해시



## Ⅰ. 개요

- 정의/개념: 임의 길이 입력을 고정 길이 값으로 압축
- **배경/필요성**: 원문 전체 비교 없이 변경 여부 판정

### 쉽게 이해하기 (학습용)

- 긴 문서에서 짧은 지문을 만들면 두 문서가 같은지 빠르게 비교할 수 있지만, 지문만 보고 원문이나 진짜 작성자를 확인할 수는 없다.

## Ⅱ. 특징

- 입력 한 비트 변화가 출력 전반에 확산한다
- 공격 목표별로 필요한 저항성이 달라진다
- 키 없는 해시는 송신자를 인증하지 못한다

### 쉽게 이해하기 (학습용)

- 공격자가 파일과 해시값을 함께 바꾸면 계산 결과가 일치하므로, 정상 해시값은 서명이나 신뢰 경로로 따로 보호해야 한다.

| 설계 요소 | 설명 |

| 상태 변환 함수 | 메시지 블록으로 내부 상태 갱신 |
| 내부 상태 | 블록별 계산 결과를 연쇄 유지 |
| 다이제스트 출력 | 최종 상태를 고정 길이로 반환 |

> 요약: 모든 입력 블록이 내부 상태에 누적

### 쉽게 이해하기 (학습용)

- 입력을 작은 조각으로 나눠 이전 계산 결과에 계속 섞고, 마지막 내부 상태에서 고정 길이 지문을 꺼낸다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant P as 배포자
    participant R as 신뢰 저장소
    participant V as 검증자
    P->>R: 정상 다이제스트 등록
    P-->>V: 검증 대상 전달
    V->>R: 정상 다이제스트 조회
    V->>V: 대상 다이제스트 계산
    V->>V: 다이제스트 비교
    alt 일치
        V-->>P: 무결성 확인
    else 불일치
        V-->>P: 변경 탐지
    end
```

| 절차 | 설명 |
|:---|:---|
| 정상 다이제스트 등록 | 신뢰 경로에 기준값 저장 |
| 검증 대상 전달 | 원본과 검증 범위를 제공 |
| 정상 다이제스트 조회 | 보호된 기준값 확보 |
| 대상 다이제스트 계산 | 같은 입력 규칙으로 해시 계산 |
| 다이제스트 비교 | 계산값과 기준값 일치 판정 |
| 무결성 확인 | 일치 시 변경 없음으로 처리 |
| 변경 탐지 | 불일치 시 대상을 거부 |

> 요약: 보호된 기준값과 계산값으로 변경 판정

### 쉽게 이해하기 (학습용)

- 파일 지문을 다시 계산하는 것보다 비교할 정상 지문을 공격자가 바꾸지 못하는 곳에서 가져오는 일이 무결성 판단의 출발점이다.

## Ⅴ. 종류 및 비교

| 판단 기준 | SHA-2 | SHA-3 | SHA-1 |
|:---|:---|:---|:---|
| 핵심 특징 | 블록별 내부 상태 갱신 | 스펀지 구조로 흡수·출력 | 160비트 출력의 구형 해시 |
| 적용 기준 | 서명·HMAC·파일 무결성 | 다른 내부 구조가 필요한 설계 | 기존 식별값 호환 검증만 |
| 주요 위험 | 입력 규칙 불일치 시 검증 실패 | 구현·프로토콜 지원 확인 | 충돌 공격으로 보안 적용 부적합 |

> 요약: 범용은 SHA-2, 구조 대안은 SHA-3

### 쉽게 이해하기 (학습용)

- SHA-1은 숫자가 길어 보여도 같은 지문을 가진 두 문서를 만들 수 있으므로 새 보안 설계에서 제외하고, 호환성과 구조 요구에 따라 SHA-2나 SHA-3를 쓴다.

## Ⅵ. 실무 사례

1. 비밀번호 저장은 솔트와 Argon2id 적용

### 쉽게 이해하기 (학습용)

- 비밀번호는 빠른 일반 해시가 아니라 사용자별 솔트와 메모리를 많이 쓰는 Argon2id를 적용해 대량 추측 비용을 높인다.

## Ⅶ. 결론

- 데이터 변경을 신뢰성 있게 탐지하기 위해 용도별 공격 저항성과 기준 해시값의 보호 방법을 검토하여, 안전한 해시 알고리즘과 검증 절차를 선택해야 한다.

### 쉽게 이해하기 (학습용)

- 해시값이 같다는 사실만 보지 말고, 충돌 공격에 안전한 알고리즘인지와 비교한 기준값이 신뢰 경로에서 왔는지를 함께 확인해야 한다.
