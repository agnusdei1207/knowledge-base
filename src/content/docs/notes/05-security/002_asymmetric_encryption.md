## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **비대칭키 암호**: 공개 가능한 키와 소유자만 보관하는 개인키를 서로 다른 역할에 사용하는 암호 방식이다.
- **키 설정**: 통신 당사자가 이후 대칭 암호에 사용할 공유 비밀이나 세션키를 만드는 과정이다.
- **전자서명**: 개인키로 전자문서의 출처와 무결성을 증명하는 기능이다.
- **사전 안전 공유 한계**: 통신 전에 대칭키를 노출 없이 상대에게 전달하기 어려운 문제이다.

</details>

- 정의/개념: 공개키•개인키로 **키 설정•전자서명**을 수행하는 **비대칭키 암호**이다.
- 배경/필요성: 대칭키 암호 방식은 송수신자 간 비밀키의 사전 안전 분배 및 관리 복잡도(Key Distribution Problem)라는 한계가 존재한다.

#### 한줄 요약

- 공개키로는 누구나 암호화할 수 있지만 대응하는 개인키 소유자만 복호화할 수 있으며, 공개키의 소유자가 누구인지 인증서로 확인해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공개키**: 암호화나 서명 검증에 사용하도록 배포하는 키이다.
- **개인키**: 복호화나 서명 생성에 사용하도록 소유자가 격리하는 키이다.
- **인증서**: 공개키•소유자•유효기간을 인증기관의 서명으로 묶어 공개키의 주인을 증명하는 전자문서이다.

</details>

- **공개키** 배포와 **개인키** 격리가 핵심이다.
- 공개키 기반 **키 설정**•**전자서명**이 핵심이다.
- **인증서**로 공개키 소유자를 검증한다.

#### 한줄 요약

- 공개키 파일만 받으면 공격자가 바꿔치기했는지 알 수 없으므로, 신뢰하는 인증기관의 서명과 유효기간을 확인한 뒤 사용한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **공개키 기반구조(Public Key Infrastructure, PKI)**: 인증서의 발급•검증•폐지를 통해 공개키와 소유자 신원을 연결하는 신뢰 체계이다.
- **하드웨어 보안 모듈(Hardware Security Module, HSM)**: 개인키를 외부로 노출하지 않고 장치 내부에서 복호화와 서명 연산을 수행하는 장치이다.
- **키 생성기**: 수학적으로 연결된 공개키•개인키 쌍을 생성하는 구성요소이다.
- **공개키•인증서 저장소**: 공개키와 소유자•유효기간 정보를 배포하는 저장소이다.
- **개인키 보호 모듈**: 개인키를 반출하지 않고 허용된 암호 연산만 수행하는 구성요소이다.
- **키 설정•서명 모듈**: 공유 비밀 설정과 전자서명 생성•검증을 수행하는 구성요소이다.

</details>

```text
비대칭 암호 구조
├─ 키 생성기
├─ 공개키•인증서 저장소
├─ 개인키 보호 모듈
└─ 키 설정•서명 모듈
```

가지의 의미: 키 생성•공개•보호•암호 연산 책임을 분리한 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 키 생성기 | **키 생성기**가 공개키•개인키 쌍 생성 |
| 공개키•인증서 저장소 | **공개키•인증서 저장소**가 공개키 소유자•유효기간 제공 |
| 개인키 보호 모듈 | **개인키 보호 모듈**이 **HSM**에서 개인키 반출 없는 암호 연산 수행 |
| 키 설정•서명 모듈 | **키 설정•서명 모듈**이 공유 비밀 설정•서명 생성 수행 |


#### 한줄 요약

- 공개키는 인증서에 바인딩하여 배포하고 개인키는 HSM 안에 격리한 채, 응용은 개인키 원본이 아니라 HSM이 수행한 복호화·서명 결과만 받는다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **키 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)**: 수신자의 공개키로 공유 비밀을 캡슐화하고 개인키로 복구하는 키 설정 방식이다.
- **폐기 상태 검증**: 인증서가 유효기간 안에 있어도 발급기관이 효력을 중단했는지 확인하는 검증이다.
- **공개•개인키 쌍 생성**: 배포할 공개키와 격리할 개인키를 함께 생성하는 단계이다.
- **공개키•인증서 게시**: 공개키와 소유자 신원 정보를 저장소에 제공하는 단계이다.
- **인증서•폐기 상태 검증**: 인증서 서명•유효기간•폐기 여부를 확인하는 단계이다.
- **공유 비밀 캡슐화**: 검증한 공개키로 공유 비밀과 캡슐화 암호문을 생성하는 단계이다.
- **공유 비밀 복구**: 수신자 개인키로 캡슐화 암호문에서 동일한 공유 비밀을 얻는 단계이다.

</details>

```text
1. 공개•개인키 쌍 생성
        │
        ▼
2. 공개키•인증서 게시
        │
        └── 인증서•폐기 상태 조회
                    │
                    ▼
3. 인증서•폐기 상태 검증
        ├─ 실패: 키 설정 중단
        └─ 성공
             │
             ▼
     4. 공유 비밀 캡슐화
             │
             └── 캡슐화 암호문 전달
                         │
                         ▼
                 5. 공유 비밀 복구
```

### 동작 원리

1. **공개•개인키 쌍 생성**: **공개•개인키 쌍 생성**으로 공개키 배포•개인키 격리를 준비한다.
2. **공개키•인증서 게시**: **PKI**에 **공개키•인증서 게시**를 수행한다.
3. **인증서•폐기 상태 검증**: **폐기 상태 검증**을 포함한 **인증서•폐기 상태 검증**을 수행한다.
4. **공유 비밀 캡슐화**: **KEM**으로 **공유 비밀 캡슐화**를 수행한다.
5. **공유 비밀 복구**: 개인키로 **공유 비밀 복구**를 수행한다.


#### 한줄 요약

- 공개키의 주인을 확인하지 않으면 공격자가 자기 자물쇠를 상대 것처럼 내밀 수 있으므로, 인증서 검증 뒤에만 공유 비밀을 만든다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **최적 비대칭 암호 패딩(Optimal Asymmetric Encryption Padding, OAEP)**: RSA 암호화에 무작위 패딩을 적용하여 반복과 구조 노출을 막는 방식이다.
- **임시 타원곡선 디피-헬먼(Elliptic Curve Diffie-Hellman Ephemeral, ECDHE)**: 연결마다 임시 타원곡선 키를 생성하여 순방향 비밀성을 제공하는 방식이다.
- **모듈 격자 기반 키 캡슐화 메커니즘(Module-Lattice-Based Key-Encapsulation Mechanism, ML-KEM)**: 모듈 격자 문제를 기반으로 양자 공격에 대응하는 키 설정 방식이다.
- **RSA-OAEP**: RSA 키 전송에 OAEP 무작위 패딩을 적용한 키 설정 방식이다.

</details>

| 공개키 키 설정 방식 | **RSA-OAEP** | **ECDHE** | **ML-KEM** |
|:---|:---|:---|:---|
| 적용 기준 | 기존 RSA 키 전송 호환 | 순방향 비밀성이 필요한 TLS | 양자 공격 대비 키 설정 |
| 핵심 특징 | **OAEP** 무작위 패딩 | 임시 키 공유 비밀 합의 | 모듈 격자 KEM |
| 한계 | 개인키 유출 시 과거 복호화 | 인증 없으면 중간자 공격 | 키•암호문 크기 증가 |

> 요약: 호환성•순방향 비밀성•양자 대응으로 선택한다.

#### 한줄 요약

- RSA-OAEP는 생성된 세션키를 암호화 전송하고, ECDHE는 양쪽이 임시 키 쌍으로 공유 비밀을 도출하며, ML-KEM은 양자 공격을 고려해 비밀을 캡슐화한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **순방향 비밀성**: 장기 개인키가 나중에 유출되어도 과거 세션키를 복구할 수 없게 하는 성질이다.
- **HSM 격리**: 개인키를 장치 밖으로 내보내지 않고 내부에서 암호 연산만 수행하게 하는 보호 방식이다.
- **FIPS 203**: 양자 내성 키 캡슐화 방식인 ML-KEM을 규정한 표준이다.
- **암호 민첩성**: 위협과 표준 변화에 맞춰 암호 알고리즘을 교체하거나 병행하는 능력이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공개키 바꿔치기 | **인증서•폐기 상태 검증** | 중간자 공격 차단 |
| 장기 개인키 노출 | **HSM 격리**•**ECDHE** | **순방향 비밀성** 확보 |
| 양자 위협 전환 | **FIPS 203**의 **ML-KEM** 병행 시험 | **암호 민첩성** 확보 |

#### 한줄 요약

- 검증된 공개키만 사용하고 개인키는 HSM에 격리하며 고가치 연결부터 양자 내성 전환을 시험한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **공개키 키 설정 방식 선택**: 호환성•순방향 비밀성•양자 위협 대응 요구에 따라 RSA-OAEP•ECDHE•ML-KEM을 결정하는 판단이다.

</details>

- 기존 호환은 **RSA-OAEP**, 순방향 비밀성은 **ECDHE**, 양자 위협 대응은 **ML-KEM**을 택하는 **공개키 키 설정 방식 선택**이 필요하다.

#### 한줄 요약

- 공개키 암호는 어려운 수학만으로 안전해지지 않으며, 공개키 주인 확인과 개인키 격리 뒤에 필요한 키 설정 방식을 선택해야 한다.
