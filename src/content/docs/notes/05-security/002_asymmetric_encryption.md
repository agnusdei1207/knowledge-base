## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비대칭 암호화(Asymmetric Encryption / Public Key Cryptography)**: 서로 수학적으로 연계되어 있으나 일방향 함수(Trapdoor One-Way Function) 특성으로 인해 한쪽에서 다른 쪽을 유도할 수 없는 **공개키(Public Key)** 와 **개인키(Private Key)** 쌍을 사용하는 암호화 방식.
- **키 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)**: 비대칭키로 대용량 데이터를 직접 암호화하지 않고, 송신자가 생성한 임의의 대칭 세션키(Symmetric Key)를 수신자의 공개키로 암호화(Encapsulate)하여 안전하게 전달하는 표준 키 교환 기법.

</details>

- 정의/개념: 누구나 알 수 있는 **공개키(암호화/서명 검증)** 와 소유자만이 보유하는 **개인키(복호화/서명 생성)** 를 수학적으로 분리하여, 사전에 비밀키를 공유하지 않은 당사자 간에도 도청 불가능한 키 교환, 기밀성 및 부인방지(Non-Repudiation) 전자서명을 제공하는 **공개키 암호 아키텍처**
- 배경/필요성: 대칭키 암호화에서 $N$명의 참여자 간 통신 시 $\frac{N(N-1)}{2}$개의 비밀키를 안전하게 사전 배포·관리해야 하는 키 배송 문제(Key Distribution Problem)와 확장성 한계를 극복할 요구

#### 한줄 요약
- 공개키와 개인키를 분리하여 사전 비밀 공유 없이도 안전한 키 교환과 전자서명 부인방지를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **순방향 비밀성(Perfect Forward Secrecy, PFS)**: 향후 서버의 장기 개인키(Long-Term Private Key)가 해킹 등으로 유출되더라도, 과거 세션마다 독립적으로 생성된 임시(Ephemeral) 대칭키를 복구할 수 없어 과거의 암호 통신 트래픽이 복호화되지 않는 특성 (ECDHE, DHE).
- **트랩도어 일방향 함수(Trapdoor One-Way Function)**: 한 방향 연산(예: 두 소수의 곱셈 $N=pq$)은 쉬우나, 역방향 연산(소인수분해)은 트랩도어(개인키 정보) 없이는 다항식 시간 내에 계산하기 불가능한 수학적 함수.

</details>

- **키 분리 구조 및 배송 문제 원천 해결**: 공개키는 누구나 열람 가능한 디렉터리(PKI)에 안전하게 게시하고, 개인키는 HSM에 격리
- **다목적 암호 서비스 동시 지원**: 기밀성을 위한 키 교환(KEM), 메시지 무결성 및 출처 인증을 위한 전자서명(Digital Signature) 동시 제공
- **수학적 난제 기반 보안성**: 소인수분해(RSA), 이산대수(Diffie-Hellman), 타원곡선 이산대수(ECDSA/ECDH), 양자내성 격자 기반(ML-KEM/ML-DSA)

#### 한줄 요약
- 공개키/개인키 분리, KEM 기반 세션키 교환, 전자서명 부인방지, ECDHE 순방향 비밀성(PFS)을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **공개키 기반구조(Public Key Infrastructure, PKI)**: 공개키가 실제 소유자의 것임을 공인인증기관(CA)의 전자서명을 통해 증명하는 X.509 인증서 발급, 검증, 폐기 생태계.
- **하드웨어 보안 모듈(Hardware Security Module, HSM)**: 비대칭 개인키가 메모리 덤프나 물리적 공격으로 유출되지 않도록 하드웨어 칩 내부에서만 키를 생성·보관하고 암호 연산 결과만을 반환하는 보안 장치 (FIPS 140-3).

</details>

```text
[ 송신자: Alice ]                                                  [ 수신자: Bob ]
 ├─ Bob의 공개키 (Public Key: PKI 검증 완료)                          ├─ Bob의 개인키 (Private Key: HSM 내 안전 보관)
 └─ KEM 엔진 (대칭 세션키 생성 및 캡슐화)                              └─ KEM 캡슐 해제 엔진
           │                                                                   ▲
           ▼ (1. Bob의 공개키로 세션키 캡슐화: Encapsulation)                 │
┌──────────────────────────────────────────────────────────────────────────────┼───────────────────┐
│ [ 공개 네트워크 전송 구간 (Insecure Public Network) ]                         │                   │
│  └─ [ 캡슐화된 키 데이터 (Ciphertext / Ephemeral Public Key) ] ──────────────┘                   │
│                                                                                                  │
│                                 (2. Bob의 개인키로 캡슐 복호화: Decapsulation) ──────────────────┘
│                                       ▼
└───────────────────────────────▶ [ 양단 간 동일한 대칭 세션키(Shared Secret) 도출 완료 ]
                                  (이후 AES-GCM 초고속 대용량 통신 개시)
```

선의 의미: 송신자가 수신자의 검증된 공개키로 대칭키를 캡슐화하여 전송하고, 수신자가 HSM 내부의 개인키로 복호화하여 공통 세션키를 수립하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **공개키 (Public Key)** | 누구나 획득 가능한 키로, 데이터 암호화 및 전자서명 검증(Verification)에 사용 | X.509 인증서 |
| **개인키 (Private Key)** | 오직 소유자만 보관하는 비밀키로, 복호화(Decryption) 및 서명 생성(Signing)에 사용 | HSM 격리 보관 |
| **공인인증기관 (CA)** | 공개키와 소유자 신원을 바인딩하여 X.509 인증서 발행 및 폐기(CRL/OCSP) 관리 | PKI Root CA |
| **KEM 엔진** | 세션키 생성 및 비대칭 암호화를 결합하여 대칭 암호화 통신 채널을 신속하게 수립 | RSA-OAEP / ML-KEM |
| **전자서명 엔진** | 메시지 해시값을 개인키로 암호화하여 송신자 신원 인증 및 위변조 방지 | ECDSA / Ed25519 |

#### 한줄 요약
- 공개키, 개인키, PKI 인증기관, KEM 엔진, 전자서명 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RSA-OAEP(Optimal Asymmetric Encryption Padding, RFC 8017)**: RSA 암호화 시 평문에 랜덤 패딩과 이중 해시 Feistel 구조를 적용하여, 동일한 평문이라도 매번 완전히 다른 암호문이 생성되도록 만들어 선택 암호문 공격(CCA2)을 방어하는 표준 패딩 기법.

</details>

```text
1. 수신자(Bob)가 비대칭 키 쌍을 생성하고, 공개키에 대해 공인 CA로부터 X.509 인증서 발급 및 게시
            │
            ▼
2. 송신자(Alice)가 Bob의 인증서를 다운로드 ➔ CA 서명 유효성 및 OCSP 폐기 여부 실시간 검증
            │
            ▼
3. Alice가 임의의 256비트 대칭 세션키를 생성하고, Bob의 검증된 공개키로 KEM(RSA-OAEP/ML-KEM) 캡슐화
            │
            ▼
4. 캡슐화된 암호문을 Bob에게 전송 ➔ Bob이 HSM 내부의 개인키로 복호화하여 대칭 세션키 복원
            │
            ▼
5. 양단 간에 동일한 대칭키 공유 완료 ➔ 이후 대용량 데이터는 AES-GCM 대칭키로 초고속 전송
```

**동작 원리**

1. **신뢰 검증**: 통신 전 상대방 공개키의 위변조 여부를 PKI 인증서 체인으로 확인
2. **세션키 캡슐화**: 무거운 비대칭 연산은 256비트 세션키 1회 교환에만 사용
3. **패딩 보안**: OAEP 패딩을 적용하여 수학적 격자 공격 및 블리헨바허(Bleichenbacher) 공격 차단
4. **개인키 격리 연산**: 수신 측은 개인키를 메모리에 노출하지 않고 HSM 내부에서 복호화 집행
5. **하이브리드 전환**: 비대칭키의 안전한 키 배송과 대칭키의 고속 데이터 전송을 결합하여 통신 완결

#### 한줄 요약
- 인증서 검증, KEM 세션키 캡슐화, 암호문 전송, 개인키 복호화, 대칭키 하이브리드 통신 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **비대칭 암호 알고리즘 세대별 비교**: 전통적 소인수분해 RSA, 고효율 타원곡선 ECC(ECDH/ECDSA), 양자내성 격자 암호 ML-KEM의 비교.

</details>

| 비교 항목 | RSA-OAEP / RSA-PSS | ECC (ECDH / ECDSA) | ML-KEM (Post-Quantum Kyber) |
|:---|:---|:---|:---|
| **수학적 난제 기반** | **큰 수의 소인수분해 (Factoring)** | **타원곡선 이산대수 문제 (ECDLP)** | **모듈 격자 상의 학습 난제 (MLWE)** |
| **동등 보안 키 길이** | **3072비트 (키 크기 큼, 연산 무거움)**| **256비트 (키 크기 극소, 초고속 연산)**| 공개키 1,184바이트 / 암호문 1,088바이트 |
| **순방향 비밀성 (PFS)**| RSA 키 교환 시 미지원 (SNDL 위협) | **ECDHE 적용 시 완벽 지원 (1회용 키)** | **ML-KEM 에페머럴 적용 시 완벽 지원** |
| **양자 공격 내성** | **취약 (쇼어 알고리즘에 의해 완전 붕괴)**| **취약 (쇼어 알고리즘에 의해 완전 붕괴)**| **영구적 안전 (NIST FIPS 203 표준)** |
| **주요 적용 영역** | 레거시 웹 인증서, 서명 시스템 | **현대 TLS 1.3, SSH, 스마트폰, 블록체인**| **차세대 TLS 1.3 하이브리드, 국가 안보**|

#### 한줄 요약
- RSA는 레거시 호환, ECC는 현대 모바일/TLS 1.3 최적화, ML-KEM은 미래 양자 공격 방어 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SNDL(Store Now, Decrypt Later) 공격**: 적대국이나 공격자가 현재의 암호화된 기밀 통신 트래픽을 대규모로 도청·저장해 두고, 향후 고성능 양자컴퓨터가 상용화되었을 때 과거 트래픽의 비대칭 키를 해독하여 기밀을 열람하는 위협.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공격자가 공개키를 위조하여 통신 중간에서 세션키를 가로채는 **중간자 공격(MITM)** | **X.509 PKI 인증서 체인 검증, 인증서 핀닝(Pinning) 및 실시간 OCSP Stapling** | 공개키 위변조 원천 차단 및 신뢰된 엔드포인트 통신 보장 |
| 서버의 장기 개인키 유출 시 과거 수집된 모든 암호 통신이 일괄 복호화되는 위험 | 정적 RSA 키 교환을 배제하고 **세션별 1회용 키를 생성하는 ECDHE(PFS)** 의무화 | 장기 키 유출 시에도 과거 트래픽 복호화 불가능(완벽한 순방향 비밀성) |
| 미래 양자컴퓨터 출현 시 현재 RSA/ECC 암호체계의 일괄 무력화 (SNDL 위협) | 기존 ECC와 양자내성암호(ML-KEM)를 결합한 **하이브리드 키 교환(X25519 + ML-KEM)** 적용 | 양자 컴퓨팅 도래 시에도 데이터 영구 기밀성 완벽 보장 |

#### 한줄 요약
- PKI 인증으로 MITM을 방어하고, ECDHE로 순방향 비밀성을 확보하며, ML-KEM 하이브리드로 양자 위협을 차단한다.

## Ⅶ. 결론

- 인터넷 신뢰 인프라의 근간인 **비대칭 암호화 기술**은 현대 전자상거래, 블록체인, TLS 보안 통신의 핵심 아키텍처이며, 실무 구현 시 **ECDHE 기반 순방향 비밀성(PFS) 표준화**, **HSM을 통한 개인키 물리적 격리**, **양자 컴퓨팅 위협에 대비한 PQC(ML-KEM/ML-DSA) 하이브리드 전환**을 통합 추진하여 장기적 관점의 무결점 암호 인프라를 완성

#### 한줄 요약
- 비대칭 암호화의 수학적 난제와 PKI 및 PQC 하이브리드 전환을 결합하여 영구적 기밀성과 부인방지를 실현한다.
