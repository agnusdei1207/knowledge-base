## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Asymmetric Encryption (비대칭 암호화)**: 암호화에 사용하는 공개키와 복호화에 사용하는 개인키가 서로 다른 암호화 방식.
- **KEM (Key Encapsulation Mechanism)**: 수신자의 공개키로 대칭 세션키를 캡슐화하여 안전하게 배송하는 공개키 교환 표준.

</details>

- 정의/개념: 공개키(암호화/검증)와 개인키(복호화/서명)의 수학적 난제 쌍을 통해 **사전 비밀키 공유 없이 안전한 키 교환과 부인방지를 제공하는 암호화 기술**
- 배경/필요성: 대칭키 암호의 $N(N-1)/2$ 키 관리 폭증 및 공용망을 통한 **대칭 비밀키 사전 배송 불가, 키 도청 위험 및 전자서명 부인방지 불가**

#### 한줄 요약
- 공개키와 개인키의 비대칭 쌍을 통해 사전 비밀키 공유 없는 안전한 키 교환과 전자서명을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Trapdoor One-Way Function (트랩도어 일방향 함수)**: 순방향 계산(공개키 연산)은 쉬우나 역방향 계산(개인키 없이 평문 복구)은 수학적으로 불가능한 함수.
- **PFS (Perfect Forward Secrecy, 순방향 비밀성)**: 서버의 장기 개인키가 유출되어도 과거 세션의 암호화 트래픽을 소급하여 복호화할 수 없는 속성.

</details>

- **키 사전 공유 불필요(Key Distribution Resolution)**: 누구나 볼 수 있는 **공개키를 인터넷에 안전하게 공개하여 키 배송 문제 완벽 해결**
- **부인방지(Non-Repudiation) 및 전자서명**: 오직 소유자만 생성 가능한 **개인키 서명을 통해 송신 사실 및 데이터 무결성 입증**
- **임시 키 기반 순방향 비밀성(PFS)**: ECDHE 등을 통해 **매 세션마다 일회용 키를 생성하여 장기 개인키 유출 시 과거 트래픽 보호**

#### 한줄 요약
- 키 배송 문제 해결, 전자서명 부인방지, 임시 키 기반 순방향 비밀성(PFS)을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Public Key vs Private Key**: 암호화 및 서명 검증에 쓰이는 공개키와 복호화 및 서명 생성에 쓰이는 개인키.

</details>

```text
[KEM 기반 비대칭 키 교환 및 하이브리드 통신 토폴로지]
|-- Alice (Client: Bob의 X.509 인증서 공개키 검증, 임시 대칭 세션키 생성 및 캡슐화)
`-- Public Insecure Network (캡슐화된 암호문 Ciphertext 전송)
`-- Bob (Server: HSM 내부 격리된 개인키로 캡슐 복호화 -> 대칭 세션키 도출)
`-- Shared Secret Established (양단 간 동일한 256비트 대칭키 도출 -> 이후 AES-GCM 초고속 통신)
```

선의 의미: 송신자가 수신자의 검증된 공개키로 대칭키를 캡슐화하여 전송하고 수신자가 HSM 내부 개인키로 복호화하여 공통 세션키를 수립하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **공개키 (Public Key)** | 누구나 획득 가능, **데이터 암호화 및 전자서명 검증(Verification)에 사용** | X.509 인증서 |
| **개인키 (Private Key)**| 오직 소유자만 보관, **복호화(Decryption) 및 서명 생성(Signing)에 사용** | HSM 격리 보관 |
| **공인인증기관 (CA)** | 공개키와 소유자 신원을 바인딩하여 **X.509 인증서 발행 및 폐기 관리** | PKI Root CA |
| **KEM 엔진** | 세션키 생성 및 비대칭 암호화를 결합하여 **대칭키 통신 채널을 신속 수립** | RSA-OAEP / ML-KEM |
| **전자서명 엔진** | 메시지 해시값을 개인키로 서명하여 **송신자 신원 인증 및 위변조 방지** | ECDSA / Ed25519 |

#### 한줄 요약
- 공개키, 개인키, PKI 인증기관, KEM 엔진, 전자서명 엔진이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **RSA-OAEP (RFC 8017)**: 평문에 랜덤 패딩과 Feistel 구조를 적용하여 동일 평문이라도 매번 다른 암호문을 생성함으로써 선택 암호문 공격을 방어하는 패딩 기법.

</details>

```text
비대칭 인증서 검증, KEM 키 캡슐화 및 대칭 통신 전환 파이프라인
        │
   1. [인증서 발급/게시] 수신자(Bob)가 비대칭 키 쌍을 생성하고 공인 CA로부터 X.509 인증서 발급
        │
   2. [인증서 신뢰 검증] 송신자(Alice)가 Bob의 인증서를 다운로드하여 CA 서명 및 OCSP 유효성 검증
        │
   3. [세션키 캡슐화] Alice가 256비트 대칭키를 생성하고 Bob의 공개키로 KEM(RSA-OAEP/ML-KEM) 캡슐화
        │
   4. [개인키 캡슐 해제] 캡슐화된 암호문을 전송받은 Bob이 HSM 내부의 개인키로 복호화하여 대칭키 획득
        │
   ▼
5. [대칭 하이브리드 전환] 양단 간 대칭키 공유 완료 후 대용량 데이터를 AES-GCM으로 초고속 통신
```

#### 한줄 요약
- 인증서 검증 → KEM 세션키 캡슐화 → 암호문 전송 → 개인키 복호화 → 대칭키 하이브리드 통신 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RSA** vs **ECC (ECDH/ECDSA)** vs **ML-KEM (Post-Quantum Kyber)**.

</details>

| 비교 항목 | RSA-OAEP / RSA-PSS | ECC (ECDH / ECDSA) | ML-KEM (Post-Quantum Kyber) |
|:---|:---|:---|:---|
| **수학적 난제 기반** | **큰 수의 소인수분해 (Factoring)** | **타원곡선 이산대수 문제 (ECDLP)** | **모듈 격자 상의 학습 난제 (MLWE)** |
| **동등 보안 키 길이** | **3072비트 (키 크기 큼, 연산 무거움)**| **256비트 (키 크기 극소, 초고속 연산)**| 공개키 1,184바이트 / 암호문 1,088바이트 |
| **순방향 비밀성 (PFS)**| RSA 키 교환 시 미지원 (SNDL 위협) | **ECDHE 적용 시 완벽 지원 (1회용 키)** | **ML-KEM 에페머럴 적용 시 완벽 지원** |
| **양자 공격 내성** | **취약 (쇼어 알고리즘에 의해 완전 붕괴)**| **취약 (쇼어 알고리즘에 의해 완전 붕괴)**| **영구적 안전 (NIST FIPS 203 표준)** |
| **주요 적용 영역** | 레거시 웹 인증서, 서명 시스템 | **현대 TLS 1.3, SSH, 스마트폰, 블록체인**| **차세대 TLS 1.3 하이브리드, 국가 안보**|

#### 한줄 요약
- RSA는 레거시 호환, ECC는 현대 모바일/TLS 1.3 최적화, ML-KEM은 미래 양자 공격 방어 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SNDL (Store Now, Decrypt Later)**: 현재 암호화된 트래픽을 대규모 수집·저장해 두고 향후 양자컴퓨터로 사후 복호화하는 국가급 도청 위협.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공격자가 공개키를 위조하여 세션키를 가로채는 **중간자 공격(MITM)** | **`X.509 PKI 인증서 체인 검증, Certificate Pinning 및 OCSP Stapling`** | 공개키 위변조 원천 차단 및 신뢰된 통신 보장 |
| 서버의 장기 개인키 유출 시 과거 트래픽이 일괄 복호화되는 위험 | 정적 RSA 키 교환을 배제하고 **`1회용 임시 키를 생성하는 ECDHE(PFS)`** 의무화 | 장기 키 유출 시에도 과거 트래픽 복호화 차단 |
| 미래 양자컴퓨터 출현 시 현재 RSA/ECC 암호의 일괄 무력화(SNDL) | 기존 ECC와 양자내성암호를 결합한 **`하이브리드 키 교환(X25519 + ML-KEM)`** 적용 | 양자 컴퓨팅 시대에도 데이터 영구 기밀성 보장 |
| 개인키 파일의 평문 저장으로 인한 서버 침해 시 키 유출 사고 | **`FIPS 140-3 Level 3 HSM (Hardware Security Module)` 격리 보관** | 개인키 외부 반출 원천 차단 및 하드웨어 보안 집행 |

#### 한줄 요약
- PKI 인증으로 MITM을 방어하고, ECDHE로 순방향 비밀성을 확보하며, ML-KEM 하이브리드로 양자 위협을 차단한다.

## Ⅶ. 결론

- 인터넷 신뢰 인프라의 근간인 **비대칭 암호화 기술은 전자상거래, 블록체인, TLS 보안 통신의 핵심 아키텍처**이며, 실무 구현 시 **ECDHE 기반 순방향 비밀성(PFS) 표준화, HSM을 통한 개인키 물리적 격리, 양자 컴퓨팅 위협에 대비한 PQC(ML-KEM/ML-DSA) 하이브리드 전환**을 통합 추진하여 장기적 관점의 무결점 암호 인프라 완성

#### 한줄 요약
- 비대칭 암호화는 공개키/개인키 쌍과 수학적 난제 기반으로 키 배송 문제를 해결하고 PKI 및 PQC와 결합하여 영구적 신뢰성을 제공한다.
