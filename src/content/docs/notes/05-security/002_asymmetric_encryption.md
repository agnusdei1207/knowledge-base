## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **비대칭키 암호**는 공개 가능한 키와 소유자만 보관하는 개인키를 서로 다른 역할에 사용하는 암호 방식이다.
- **키 설정**은 통신 당사자가 이후 대칭 암호에 사용할 공유 비밀이나 세션키를 만드는 과정이다.

</details>

- 정의/개념: 공개키•개인키로 **키 설정•전자서명**을 수행하는 **비대칭키 암호**이다.
- 배경/필요성: 대칭키의 **사전 안전 공유 한계** 해소가 필요하다.

#### 한줄 요약

- 누구나 우편함에 편지를 넣지만 소유자만 열 수 있듯 공개키는 배포하고 개인키는 숨기며, 우편함의 실제 주인이 누구인지 인증서로 확인해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공개키**는 암호화나 서명 검증에 사용하도록 배포하는 키이다.
- **개인키**는 복호화나 서명 생성에 사용하도록 소유자가 격리하는 키이다.
- **키 설정**은 공개키 방식으로 이후 사용할 공유 비밀을 만드는 기능이다.
- **전자서명**은 개인키로 전자문서의 출처와 무결성을 증명하는 기능이다.
- **인증서**는 공개키•소유자•유효기간을 인증기관의 서명으로 묶어 공개키의 주인을 증명한다.

</details>

- 공개키 배포와 **개인키 격리**가 핵심이다.
- 공개키 기반 **키 설정•전자서명**이 핵심이다.
- 인증서 기반 **공개키 소유자 검증**이 핵심이다.

#### 한줄 요약

- 공개키 파일만 받으면 공격자가 바꿔치기했는지 알 수 없으므로, 신뢰하는 인증기관의 서명과 유효기간을 확인한 뒤 사용한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **공개키 기반구조(Public Key Infrastructure, PKI)**는 인증서의 발급•검증•폐지를 통해 공개키와 소유자 신원을 연결하는 신뢰 체계이다.
- **하드웨어 보안 모듈(Hardware Security Module, HSM)**은 개인키를 외부로 노출하지 않고 장치 내부에서 복호화와 서명 연산을 수행한다.

</details>

```text
비대칭 암호 구조
├─ 키 생성기
├─ 공개키•인증서 저장소
├─ 개인키 보호 모듈
└─ 키 설정•서명 모듈
```

가지의 의미: 키 생성•공개•보호•암호 연산 책임을 분리한 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 키 생성기 | **공개키•개인키 쌍** 생성 |
| 공개키•인증서 저장소 | **공개키 소유자•유효기간** 제공 |
| 개인키 보호 모듈 | **개인키 반출 없는 암호 연산** 수행 |
| 키 설정•서명 모듈 | **공유 비밀 설정•서명 생성** 수행 |


#### 한줄 요약

- 공개키는 이름표가 붙은 자물쇠처럼 배포하고 개인키는 HSM 안에 둔 채, 응용은 열쇠 원본이 아니라 HSM이 만든 복호화•서명 결과만 받는다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **키 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)**은 수신자의 공개키로 공유 비밀을 캡슐화하고 개인키로 복구하는 키 설정 방식이다.
- **폐기 상태 검증**은 인증서가 유효기간 안에 있어도 발급기관이 효력을 중단했는지 확인한다.

</details>

```text
1. 공개•개인키 쌍 생성
        │
        ▼
2. 공개키•인증서 게시
        │
        └── 인증서•폐기 상태 조회
                    │
                    ▼
3. 인증서•폐기 상태 검증
        ├─ 실패: 키 설정 중단
        └─ 성공
             │
             ▼
     4. 공유 비밀 캡슐화
             │
             └── 캡슐화 암호문 전달
                         │
                         ▼
                 5. 공유 비밀 복구
```

**동작 원리**

1. **공개•개인키 쌍 생성**: 공개키 배포•개인키를 격리한다.
2. **공개키•인증서 게시**: 키와 소유자 신원 정보를 제공한다.
3. **인증서•폐기 상태 검증**: 서명•유효기간•폐기 여부를 판정한다.
4. **공유 비밀 캡슐화**: 검증 공개키로 비밀과 암호문을 생성한다.
5. **공유 비밀 복구**: 개인키로 동일 비밀을 복구한다.


#### 한줄 요약

- 공개키의 주인을 확인하지 않으면 공격자가 자기 자물쇠를 상대 것처럼 내밀 수 있으므로, 인증서 검증 뒤에만 공유 비밀을 만든다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **최적 비대칭 암호 패딩(Optimal Asymmetric Encryption Padding, OAEP)**은 RSA 암호화에 무작위 패딩을 적용하여 반복과 구조 노출을 막는다.
- **임시 타원곡선 디피-헬먼(Elliptic Curve Diffie-Hellman Ephemeral, ECDHE)**은 연결마다 임시 타원곡선 키를 생성하여 순방향 비밀성을 제공한다.
- **모듈 격자 기반 키 캡슐화 메커니즘(Module-Lattice-Based Key-Encapsulation Mechanism, ML-KEM)**은 모듈 격자 문제를 기반으로 양자 공격에 대응하는 키 설정 방식이다.

</details>

| 공개키 키 설정 방식 | RSA-OAEP | ECDHE | ML-KEM |
|:---|:---|:---|:---|
| 적용 기준 | 기존 **RSA 키 전송 호환** | **순방향 비밀성**이 필요한 TLS | **양자 공격 대비 키 설정** |
| 핵심 특징 | **RFC 8017 RSA-OAEP** | **임시 키 공유 비밀 합의** | **FIPS 203 ML-KEM** |
| 한계 | 개인키 유출 시 **과거 복호화** | 인증 없으면 **중간자 공격** | **키•암호문 크기 증가** |

> 요약: 호환성•순방향 비밀성•양자 대응으로 선택한다.

#### 한줄 요약

- RSA-OAEP는 정한 열쇠를 포장하고, ECDHE는 양쪽이 임시 재료로 새 열쇠를 만들며, ML-KEM은 양자 공격을 고려해 비밀을 캡슐화한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **순방향 비밀성**은 장기 개인키가 나중에 유출되어도 과거 세션키를 복구할 수 없게 하는 성질이다.
- **HSM 격리**는 개인키를 장치 밖으로 내보내지 않고 내부에서 암호 연산만 수행하게 하는 보호 방식이다.
- **FIPS 203**은 양자 내성 키 캡슐화 방식인 ML-KEM을 규정한다.
- **암호 민첩성**은 위협과 표준 변화에 맞춰 암호 알고리즘을 교체하거나 병행하는 능력이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **공개키 바꿔치기** | **인증서•폐기 상태 검증** | **중간자 공격 차단** |
| **장기 개인키 노출** | **HSM 격리•임시 키 합의** | **과거 세션 보호** |
| **양자 위협 전환** | **FIPS 203 ML-KEM 병행 시험** | **암호 민첩성** 확보 |

#### 한줄 요약

- 검증된 공개키만 사용하고 개인키는 HSM에 격리하며 고가치 연결부터 양자 내성 전환을 시험한다.

## Ⅶ. 결론

- 순방향 비밀성은 **ECDHE**, 양자 위협 대응은 **ML-KEM**을 선택한다.

#### 한줄 요약

- 공개키 암호는 어려운 수학만으로 안전해지지 않으며, 공개키 주인 확인과 개인키 격리 뒤에 필요한 키 설정 방식을 선택해야 한다.
