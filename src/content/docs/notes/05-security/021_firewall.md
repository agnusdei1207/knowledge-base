## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **방화벽(Firewall)**: 상이한 보안 수준을 가진 네트워크 영역(신뢰 영역인 내부망 vs 비신뢰 영역인 외부 인터넷) 간의 경계에 위치하여, 사전에 정의된 보안 정책 룰셋(Rule Set)에 따라 인가된 트래픽만을 선별적으로 통과시키고 비인가 트래픽은 하드웨어/소프트웨어 레벨에서 차단(Drop/Reject)하는 1차 경계 방어 시스템.
- **DMZ(Demilitarized Zone / 완충 구역)**: 외부 인터넷에 공개되어야 하는 웹/메일/DNS 서버를 내부 핵심 데이터베이스망과 물리적/논리적으로 엄격히 분리하여, 공개 서버가 침해되더라도 내부망으로의 횡적 이동(Lateral Movement)을 차단하는 완충 보안 영역.

</details>

- 정의/개념: L3/L4 5-Tuple(출발지/목적지 IP, 포트, 프로토콜) 검사에서 출발하여, TCP 세션 연결 상태를 추적하는 **상태기반 검사(Stateful Inspection)**, L7 애플리케이션 페이로드와 위협 패턴을 심층 분석하는 **차세대 방화벽(NGFW: Next-Generation Firewall)** 으로 진화한 **네트워크 접근 통제 아키텍처**
- 배경/필요성: 단순 IP/포트 차단만으로는 80(HTTP), 443(HTTPS) 표준 웹 포트에 은닉되어 인입되는 악성코드, 웹쉘, C2 통신 및 비인가 SaaS 애플리케이션을 탐지할 수 없는 레거시 방화벽의 한계를 극복할 요구

#### 한줄 요약
- 5-Tuple 헤더, TCP 세션 상태 테이블, L7 심층 DPI를 결합하여 인가된 트래픽만을 선별 통제한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 거부 정책(Default Deny)**: 방화벽 정책 목록의 최하단(Bottom)에 `ANY-ANY-DENY` 규칙을 배치하여, 상위 정책에서 명시적으로 허용(Explicit Allow)되지 않은 모든 인바운드/아웃바운드 패킷을 무조건 폐기하는 보안 기본 원칙.
- **심층 패킷 분석(Deep Packet Inspection, DPI)**: 패킷의 L3/L4 헤더뿐만 아니라 L7 애플리케이션 페이로드(Payload) 내부의 실제 프로토콜 시그니처와 악성 바이너리 패턴을 전수 분석하여 애플리케이션 종류(App-ID)를 식별하는 기술.

</details>

- **다계층 심층 검사 (L3~L7)**: 5-Tuple IP/Port 정적 필터링 $\rightarrow$ TCP 3-Way Handshake 세션 테이블 추적 $\rightarrow$ L7 App-ID 및 IPS 시그니처 분석
- **상태 추적 기반 비대칭 오버헤드 절감**: 최초 세션 수립 시에만 룰셋 전체를 Top-down 검사하고, 이후 정상 세션의 인바운드 응답 패킷은 상태 테이블(State Table) 매칭으로 즉시 고속 포워딩
- **SSL/TLS 복호화 가시성(SSL Inspection)**: 암호화된 HTTPS 트래픽을 방화벽 내부에서 프록시 종단하여 복호화한 후 악성코드 및 데이터 유출 검사 수행

#### 한줄 요약
- L3~L7 다계층 검사, 상태 테이블 기반 고속 세션 추적, Default Deny 원칙, SSL 복호화 가시성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **세션 상태 테이블(State Table)**: 활성화된 TCP/UDP/ICMP 연결의 5-Tuple 정보, 시퀀스 번호(Seq/Ack), 연결 상태(SYN_SENT, ESTABLISHED), 만료 타이머(Timeout)를 메모리에 유지하여 정상적인 반환 트래픽을 자동 승인하는 동적 캐시 테이블.

</details>

```text
[ 외부 인터넷 (Untrusted Public Network) ]
                      │
                      ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 차세대 방화벽 (NGFW Engine: Next-Generation Firewall) ]                │
│  ├─ 1. 패킷 파서 & 5-Tuple 추출 ── (L3/L4 IP 및 Port 확인)               │
│  │                                                                      │
│  ├─ 2. 상태 검사 엔진 (Stateful Engine) ──▶ [ 세션 상태 테이블 (State Table) ]
│  │     └─ (기존 세션 일치 시 ➔ 룰셋 검사 우회 후 즉시 고속 통과)          │
│  │                                                                      │
│  ├─ 3. [신규 세션] Top-Down 정책 룰셋 엔진 ── (규칙 순차 매칭 / Default Deny)│
│  │                                                                      │
│  ├─ 4. SSL 복호화 프록시 (SSL Inspection) ── (암호화 해제)             │
│  │                                                                      │
│  └─ 5. L7 DPI & App-ID 엔진 ── (실제 응용 식별: BitTorrent, Zoom, C2 차단)│
└──────────────────┬──────────────────────────────────┬───────────────────┘
                   │                                  │
                   ▼ (보안 구역 격리)                 ▼ (핵심 보호 구역)
        [ DMZ Zone (공개 웹/DNS 서버) ]    [ 내부 업무망 (Trust LAN & DB 서버) ]
```

선의 의미: 인입된 패킷이 5-Tuple 추출, 상태 테이블 대조, 정책 룰셋 평가, SSL 복호화 및 L7 DPI 검사를 거쳐 DMZ 또는 내부망으로 선별 포워딩되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **5-Tuple 파서** | L3/L4 헤더(출발지/목적지 IP, 포트, TCP 플래그)를 고속 추출하여 1차 정적 검사 | L3/L4 Filter |
| **세션 상태 테이블** | 기 수립된 세션의 TCP Sequence 번호 및 상태를 추적하여 스푸핑/재전송 차단 | State Table |
| **정책 룰셋 엔진** | 관리자가 구성한 ACL 규칙을 최상단부터 순차(Top-Down) 평가하여 최종 정책 집행 | Policy Engine |
| **SSL 복호화 엔진** | 프록시 인증서를 사용하여 인바운드/아웃바운드 HTTPS 트래픽을 실시간 복호화 | SSL Inspection |
| **L7 DPI / App-ID** | 포트 번호와 무관하게 페이로드 시그니처를 분석하여 실제 응용 프로그램 식별 및 차단 | App-ID Engine |

#### 한줄 요약
- 5-Tuple 파서, 세션 상태 테이블, 정책 룰셋 엔진, SSL 복호화기, L7 DPI App-ID 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Top-Down 순차 매칭(Top-Down First-Match Rule)**: 방화벽 정책 평가 시 1번 규칙부터 순서대로 평가하여 최초로 조건이 일치하는(First Match) 규칙의 액션(Allow/Deny)을 즉시 적용하고 하위 규칙 평가는 종료하는 정책 실행 원칙.

</details>

```text
1. 신규 패킷이 방화벽 인그레스 인터페이스로 인입 ➔ L3/L4 헤더(5-Tuple) 추출
            │
            ▼
2. 세션 상태 테이블(State Table) 조회 ➔ [기존 ESTABLISHED 세션 일치 시] ➔ 4단계로 즉시 이동
            │
            ├─ [일치하는 기존 세션 없음: 신규 세션 요청(TCP SYN)]
            ▼
3. 방화벽 정책 룰셋을 최상단(Top)부터 순차 평가 ➔ [일치 규칙 매칭: Allow] ➔ 상태 테이블에 신규 세션 등록
            │     └─ [일치 규칙 없음: Default Deny] ➔ 패킷 즉시 폐기(Drop) 및 감사 로그 기록
            ▼
4. [차세대 보안 검사] SSL Inspection 활성화 트래픽인 경우 복호화 후 L7 DPI 및 IPS 시그니처 정밀 스캔
            │
            ├─ [L7 악성 위협 / 비인가 앱 탐지] ➔ 세션 강제 리셋(TCP RST) 및 차단
            ▼
5. [모든 검사 통과] ➔ NAT 변환 및 라우팅 테이블 참조하여 대상 네트워크 인터페이스로 최종 포워딩
```

**동작 원리**

1. **헤더 고속 파싱**: L3 IP 주소와 L4 TCP 플래그(SYN, ACK, FIN, RST) 추출
2. **세션 장부 대조**: 기존 세션의 반환 패킷은 룰셋 평가를 생략하여 ASIC 하드웨어 레벨 고속 포워딩
3. **정책 우선순위 집행**: 신규 연결에 대해 구체적인 규칙부터 일반 규칙 순으로 First-Match 판정
4. **페이로드 심층 검사**: 포트 기반 우회를 차단하기 위해 페이로드 디코딩 및 악성코드 스캔
5. **동적 세션 수명 관리**: TCP FIN/RST 수신 또는 유휴 시간 만료(Inactivity Timeout) 시 테이블 엔트리 자동 회수

#### 한줄 요약
- 5-Tuple 추출, 상태 테이블 대조, Top-Down 룰 매칭, SSL 복호화 및 L7 DPI 검사, 최종 포워딩 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **방화벽 3세대 발전 비교**: 1세대 정적 패킷 필터링, 2세대 상태기반 방화벽, 3세대 차세대 방화벽(NGFW)의 기능 및 성능 비교.

</details>

| 비교 항목 | 1세대 패킷 필터링 (Packet Filter) | 2세대 상태기반 방화벽 (Stateful) | 3세대 차세대 방화벽 (NGFW) |
|:---|:---|:---|:---|
| **검사 계층** | **L3 / L4 (네트워크 / 전송 계층)** | **L3 / L4 + 세션 상태 추적** | **L3 ~ L7 (애플리케이션 계층 전수 검사)**|
| **검사 기준** | **단순 5-Tuple (IP, Port, Protocol)** | **5-Tuple + TCP 세션 연결 상태** | **App-ID, User-ID, 콘텐츠(DPI), IPS 통합** |
| **처리 성능** | **초고속 (하드웨어 ASIC 기반)** | **빠름 (State Table 기반 고속 통과)** | 중간 (DPI 및 SSL 복호화로 연산 부하 큼) |
| **포트 우회 공격 방어**| **불가 (80 포트로 유입되는 악성코드 허용)**| 불가 (정상 TCP 핸드셰이크 시 통과) | **완벽 방어 (실제 앱 페이로드 식별 차단)** |
| **주요 적용 영역** | 백본 라우터 ACL, 대용량 트래픽 1차 정제 | **엔터프라이즈 레거시 경계 방화벽** | **현대 기업 경계망, 클라우드 DMZ, 데이터센터**|

#### 한줄 요약
- 1세대는 초고속 정적 필터링, 2세대는 세션 추적 표준, 3세대 NGFW는 L7 DPI 및 SSL 복호화 통합 보안이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **음영 규칙(Shadowed Rule / Rule Shadowing)**: 방화벽 정책 목록에서 상위에 포괄적인 허용 규칙(예: `ALLOW ANY`)이 위치하여, 하위에 정의된 세부 차단 규칙(예: `DENY Port 22`)이 영구히 평가되지 못하고 무력화되는 정책 구성 오류.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 상위 포괄 룰로 인해 하위 보안 정책이 평가되지 않는 **음영 규칙(Shadowed Rule) 및 정책 사각지대** | **자동화된 방화벽 정책 감사(Firewall Policy Audit) 툴 도입 및 정기적 미사용/중복 룰 정제** | 정책 우회 경로 원천 제거 및 룰셋 평가 지연시간 단축 |
| DMZ 웹 서버 침해 후 공격자가 내부 DB망으로 직결 침투하는 **단일 방화벽 붕괴 및 횡적 이동** | **외부망-DMZ, DMZ-내부망을 서로 다른 벤더로 이중 격리하는 2계층 방화벽(Double DMZ)** 구성 | 1차 방화벽 침해 시에도 2차 방화벽에 의한 내부 데이터베이스망 영구 보호 |
| 443(HTTPS) 암호화 트래픽 내부에 은닉된 **악성코드 및 C2 통신을 탐지하지 못하는 가시성 부재** | **NGFW 전용 SSL/TLS 복호화(SSL Forward Proxy) 가속 카드 탑재 및 선택적 검사** | 암호화 트래픽 내 위협 100% 탐지 및 복호화 성능 병목 해소 |

#### 한줄 요약
- 룰 감사로 음영 규칙을 제거하고, Double DMZ로 내부망을 보호하며, SSL Inspection으로 암호화 위협을 제거한다.

## Ⅶ. 결론

- 엔터프라이즈 네트워크 인프라의 가장 기본적인 1차 방어선인 **방화벽 및 차세대 방화벽(NGFW) 아키텍처**는 제로 트러스트(Micro-Segmentation)로 진화하는 현대 보안의 핵심 기반이며, 실무 구현 시 **엄격한 Default Deny 원칙 준수**, **Double DMZ 기반 계층형 망 분리**, **SSL 복호화 및 L7 App-ID 정책 고도화**를 통합 구축하여 무결점 경계 접근 통제 환경을 완성

#### 한줄 요약
- 상태기반 세션 추적과 L7 App-ID/DPI 심층 검사 및 Default Deny 정책을 통해 고신뢰 경계 보안을 실현한다.
