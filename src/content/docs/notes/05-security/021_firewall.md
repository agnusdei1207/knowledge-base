## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **방화벽 (Firewall)**: "허락된 놈만 들어와!" 하고 네트워크 관문에 서서, 정해진 규칙(보안 정책)대로 패킷을 팩트로 차단하거나 허용하는 문지기 시스템이다.
- **DMZ (비무장지대)**: "외부 손님은 거실(DMZ)까지만 오고, 안방(내부망)은 절대 들어오지 마!" 하고 공개 서버를 철저히 격리 배치하는 완충 보안 구역이다.

</details>

- 정의: 네트워크 경계에서 5-Tuple(IP/Port), 세션 상태, L7 응용 데이터를 정책 기반으로 검사해 트래픽을 통제하는 팩트 보안 시스템이다.
- 배경: 이런 경계 문지기가 없으면 외부의 비인가 해커와 악성코드가 안방(내부망)까지 프리패스로 밀고 들어와 데이터를 팩트로 다 털어가기 때문이다.

#### 한줄 요약

- 성문 앞에서 통행증 검사하는 팩트 경비원이다. 규정에 없는 놈은 절대 안으로 안 들여보내고 모조리 쳐낸다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **기본 거부 (Default Deny)**: 방화벽 룰 맨 밑바닥에 깔려있는 절대 규칙으로, "내가 위에서 명시적으로 허락하지 않은 놈은 이유 불문하고 싹 다 팩트로 버려(Drop)!"라는 원칙이다.
- **동서 트래픽 (East-West)**: 외부에서 들어오는 거(남북) 말고, 내부 서버끼리 핑퐁하는(동서) 수평 트래픽이다. 해커가 하나 털고 옆으로 옮겨가는 걸 팩트로 막으려고 통제한다.

</details>

- **팩트 다계층 검사**: 단순 IP/Port 검사부터 L7 애플리케이션 위협 서명(DPI) 분석까지 싹 다 까서 팩트로 검사한다.
- **팩트 기본 거부**: 룰셋을 위에서부터 차례로(Top-down) 검사하고, 하나라도 허용 룰에 안 걸리면 맨 밑에서 팩트로 기본 거부(Drop/Reject) 처리한다.
- **팩트 측면 방어**: 뚫려도 옆으로 못 퍼지게 내부망끼리의 수평 침투(동서 트래픽)를 잘게 쪼개서 통제(마이크로 세그멘테이션)한다.

#### 한줄 요약

- 일단 다 차단(기본 거부)하고 보는 게 팩트 원칙이며, 뚫렸을 때를 대비해 내부 서버끼리 통신하는 것도 칸막이를 쳐서 막는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 기반 검사 (Stateful Inspection)**: "아, 쟤 아까 내가 허락해서 나간 놈이네." 하고 세션 장부(State Table)를 기억해 둬서, 돌아오는 답장은 깐깐한 룰셋 검사 없이 팩트로 프리패스시켜 주는 기능이다.
- **NAT (네트워크 주소 변환)**: 외부로 나갈 때 회사 내부의 사설 IP를 공인 IP 하나로 바꿔치기해서 "우리 집 내부 구조 숨기기 + IP 절약"을 팩트로 달성한다.
- **앱/위협 검사 (DPI)**: 80번 포트(웹)라고 우기고 들어와도, 택배상자(페이로드)를 다 까봐서 게임이나 토렌트면 팩트로 쳐내는 차세대 엔진이다.

</details>

```text
[ 방화벽 팩트 통제 아키텍처 ]

[ 1. 정책 룰셋 엔진 ] ── (위에서부터 한 줄씩 "IP 1.1 허용, 2.2 차단" 팩트 매칭함)
      │
      ▼
[ 2. 상태 검사 및 NAT 변환 ] ── (기존 세션 장부 팩트 확인하고, 나갈 때 IP 바꿔치기함)
      │
      ▼
[ 3. L7 앱 및 위협 탐지 (NGFW) ] ── (포트 속이고 들어오는 악성코드나 앱을 내용물 까서 팩트로 잡아냄)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **정책 룰셋 엔진** | 위에서 아래로(Top-down) 검사하며 **허용 안 된 놈은 기본 거부로 팩트 차단함** | Rules |
| **상태 기반 및 NAT** | 나갔던 놈은 장부(State) 보고 들여보내고, **외부로 나갈 때 내부 IP를 팩트로 세탁함** | State |
| **L7 위협 탐지 엔진** | 가방(페이로드) 안을 뒤져서 **진짜 앱이 뭔지 식별하고 악성 서명을 팩트로 쳐냄** | DPI |

#### 한줄 요약

- 룰대로 차단하고 $\to$ 나갔던 놈은 기억해 두고 $\to$ 내용물까지 팩트로 싹 다 뜯어보는 문지기 3종 세트다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **5-Tuple (5-튜플)**: 택배 겉면에 적힌 '출발지 IP, 도착지 IP, 출발지 포트, 도착지 포트, 프로토콜' 이 5가지 핵심 팩트 정보 세트다.

</details>

```text
[ 방화벽 패킷 팩트 검사 및 상태 처리 흐름 ]

┌──────────────────────────────┐
│ 1. [신규 패킷 수신 및 5-Tuple 팩트 추출]
│ ("누가 어디서 몇 번 포트로 왔냐? 헤더 까보자")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [세션 상태 장부(State Table) 팩트 대조]
│ ("아까 나간 놈의 답장이면 룰셋 검사 스킵하고 팩트 프리패스!")
└──────────────┬───────────────┘
               ▼ (장부에 없는 처음 온 놈이면)
┌──────────────────────────────┐
│ 3. [Top-Down 룰셋 및 L7 위협 팩트 검사]
│ (허용 룰이 있는지 1번부터 싹 훑고, 가방 내용물(L7) 검사해서 악성 쳐냄)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [세션 상태 장부 팩트 갱신 및 통과]
│ (통과된 놈은 다음부터 빠르게 들여보내게 장부에 올리고 문 열어줌)
└──────────────────────────────┘
```

### 동작 원리

1. 헤더 추출: 수신 패킷의 5-Tuple 정보를 추출해 팩트를 파악함.
2. 상태 장부 대조: 기존 세션 상태 테이블(State Table)에 존재하는 놈이면 즉시 팩트로 허용함.
3. 룰셋 및 위협 검사: 신규 세션에 대해 Top-down 정책 매칭을 수행하고 L7 위협/앱 패턴을 팩트로 심사함.
4. 장부 갱신: 검사를 통과하면 세션 상태 테이블에 새로 등록(State Update)하고 목적지로 팩트 전달함.

#### 한줄 요약

- 헤더 까고 $\to$ 아는 놈인지 확인하고 $\to$ 처음이면 룰셋 검사 빡세게 하고 $\to$ 통과되면 장부에 팩트로 적어둔다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패킷 필터 (1세대)**: 딱 택배 겉면의 보내는 사람(IP), 받는 사람(IP/Port)만 보고 차단하는 엄청 빠르지만 팩트로 무식한 초창기 방화벽이다.
- **상태 기반 방화벽 (2세대)**: 1세대보다 똑똑하게 세션 장부를 만들어서 "아까 나간 놈이네" 하고 상태를 팩트로 기억해 주는 방화벽이다.
- **차세대 방화벽 (NGFW, 3세대)**: 겉면(IP)은 물론이고 택배상자 내용물(L7)까지 다 뜯어봐서 악성코드, 앱 종류, 유저 ID까지 싹 다 팩트로 털어버리는 끝판왕이다.

</details>

| 방화벽 세대 | **패킷 필터 (1세대)** | **상태 기반 방화벽 (2세대)** | **차세대 방화벽 (NGFW, 3세대)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **택배 겉면(IP)만 보는 대충 경비원** | **출입 장부(상태) 적어두는 깐깐한 경비원** | **택배상자 다 뜯어보는 X-ray 검색대** |
| 핵심 기술 원리 | L3/L4 헤더(5-Tuple)만 딱 보고 **빠르게 정적 필터링 차단을 팩트로 꽂음** | TCP 세션 연결 상태를 테이블(장부)로 관리하여 **동적 추적으로 팩트 검사 오버헤드를 줄임** | IPS, DPI 등을 통합해 **가방 내용물(L7)을 뜯어서 실제 앱과 악성 여부를 팩트로 심사함** |
| 적용(최고 장점) | 통신사 망에서 대량의 단순 트래픽을 **속도 지연 1도 없이 쳐낼 때 팩트로 씀** | 대부분의 일반적인 네트워크 경계에서 **기본적이고 표준적인 방어막으로 팩트로 씀** | 웹포트(80, 443)에 숨어 들어오는 지능형 최신 해킹 공격을 **원천 팩트 차단할 때 씀** |
| 치명적 한계 | 포트 번호를 속이거나 내용물에 교묘히 숨긴 L7 해킹 공격은 **팩트로 절대 못 잡음** | 좀비 PC 수만 대가 가짜 세션만 계속 걸면 **상태 테이블 장부가 꽉 차서 장비가 뻗어버림** | 암호화 트래픽(HTTPS)까지 다 복호화해서 뜯어보느라 **장비 성능(CPU)이 팩트로 심하게 갈려 나감** |

#### 한줄 요약

- 속도가 깡패면 1세대, 무난한 건 2세대, 웹 해킹 다 잡고 싶으면 돈 많이 주고 3세대(NGFW) 팩트로 달아라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **음영 규칙 (Shadowed Rule)**: 방화벽 룰 1번에 "모두 허용"을 해놓고 10번에 "해커 차단"을 넣으면, 1번에서 다 팩트로 통과돼서 10번 차단 룰은 영원히 씹히게 되는 뻘짓 오류다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 윗줄 룰에서 다 허용돼서 밑에 적어둔 **차단 룰이 팩트로 씹힘 (음영 규칙)** | 방화벽 정책이 순차(Top-down) 평가되는데, 넒은 허용 룰을 위쪽에 배치하는 팩트 실수를 함 | 안 쓰는 룰(Orphaned)과 씹히는 룰(Shadowed)을 쳐내는 **정기적 '룰셋 감사(Rule Audit)' 팩트 강제** | 정책 우회 구멍 소거 및 검사 속도 향상, 팩트 뻘짓 차단 |
| 해커가 공개 웹서버(DMZ) 하나 털고 **내부 핵심 DB망까지 팩트로 직진함** | 외부망-DMZ-내부망 간에 제대로 된 경계 방어선(Zone 격리)을 팩트로 안 쳐놓음 | Zone 기반 철저한 격리 및 내부망 진입 전 **2중 방화벽(Double DMZ) 팩트 통제 구축** | 외부 공개 서버가 털리더라도, 핵심망으로의 수평 이동(Lateral Movement) 팩트 완전 차단 |
| 정상 접속인 척 80/443 포트로 **암호화 통신 안에 악성코드를 팩트로 숨김** | 3세대 방화벽이 택배상자는 뜯었는데, 내용물이 자물쇠(SSL)로 잠겨 있어서 팩트로 못 봄 | 방화벽 안에서 트래픽 압축을 직접 풀어보는 **SSL/TLS 복호화(SSL Inspection) 팩트 적용** | 암호화 패킷 내 악성 코드 및 유출 통제를 통한 눈먼 방화벽(Blind Spot) 팩트 제거 |

#### 한줄 요약

- 위에서부터 씹히는 룰(음영 규칙) 지우고, 내부망 들어올 때 방화벽 한 번 더 치고, 암호화된 트래픽도 강제로 까서 팩트로 봐라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 보안 요구수준에 따라 헤더 통제는 **패킷 필터**, 세션 추적은 **상태 기반**, L7 위협 방어는 **차세대 방화벽(NGFW)** 을 팩트로 선택 적용하고, **음영 규칙(Shadowed)** 감사와 **기본 거부(Default Deny)** 를 강제하는 절대적 경계 방어 기조를 확립함

#### 한줄 요약

- 네트워크 방어의 최전선이다. 허용되지 않은 건 무조건 차단하는 기본 원칙(Default Deny)이 팩트 생명이다.
