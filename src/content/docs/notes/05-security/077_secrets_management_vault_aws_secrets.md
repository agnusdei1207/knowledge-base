## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **비밀 관리(Secrets Management)**: 데이터베이스 비밀번호, API 키, SSH 키, TLS 증명서 등 자격 증명의 라이프사이클(저장, 발급, 회전, 폐기, 감사)을 암호화 중앙 통제하는 보안 체계이다.
- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 비밀 관리 시스템이 워크로드 및 제3자 솔루션과 자격 증명을 보안적으로 교환하는 통신 인터페이스이다.
- **하드코딩 비밀(Hardcoded Secrets)**: 소스코드, Dockerfile, Git 저장소에 비밀번호나 자격 증명을 평문으로 포함시키는 심각한 보안 취약점 상태이다.

</details>

- 정의/개념: 비밀 관리는 분산 클라우드 및 온프레미스 환경에서 워크로드가 필요한 암호화 자격 증명을 하드코딩 없이 안전하게 동적 발급받고 자동으로 교체(Rotation)하는 중앙 암호 통제 체계이다.
- 배경/필요성: Git 저장소 공개, 컨테이너 이미지 복제로 인한 **하드코딩 비밀** 유출 사고를 방지하고, 장기 유휴 자격(Long-lived Credentials)에 따른 침해 위험을 근본적으로 축소하기 위함이다.

#### 한줄 요약

- 코드 하드코딩을 배제하고, 워크로드 신원 인증 기반으로 단기 유효 자격 증명을 동적 발급 및 회전•폐기하는 중앙 통제 솔루션이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **워크로드 신원(Workload Identity)**: K8s Service Account, AWS IAM Role, OIDC 토큰 기반으로 애플리케이션 및 마이크로서비스의 고유한 신원을 식별하는 기술이다.
- **부트스트랩(Bootstrap)**: 신규 워크로드가 최초 기동 시 최초 인증용 신원 토큰(Vault AppRole 등)을 안전하게 수령받아 초기화하는 보안 절차이다.
- **오픈아이디 커넥트(OpenID Connect, OIDC)**: OAuth 2.0 기반으로 워크로드 간 신원 정보를 토큰화하여 안전하게 상호 인증하는 프로토콜이다.
- **공개키 기반구조(Public Key Infrastructure, PKI)**: 비밀 관리 도구 내에서 동적 온디맨드 TLS/SSL 인증서를 자동 생성 및 발급하는 체계이다.
- **동적 비밀(Dynamic Secrets)**: 워크로드의 자원 접근 요청 시점에 실시간 생성되고, 임무 종료 후 자동 소멸되는 일회성 단기 자격 증명이다.
- **리스(Lease)**: 발급된 동적 비밀에 부여된 임대 유효기간이며, TTL 연장 또는 조기 폐기를 관제하는 암호학적 계약 단위이다.
- **유효 시간(Time to Live, TTL)**: 동적 자격 증명이 실질적으로 작동할 수 있도록 제한된 수명 시간이다.

</details>

- **워크로드 신원**과 **OIDC**, **PKI** 기반 부트스트랩을 연동하여 장기 고정 비밀번호 생성을 완전히 배제한다.
- 요청 시마다 생성되는 **동적 비밀**과 짧은 **TTL**을 부여하여 탈취된 자격 증명의 악용 시간 창을 극도로 단축한다.
- **리스** 시스템을 통해 발급 시점부터 자동 만료 및 긴급 폐기(Revocation)까지 라이프사이클 감사 추적성을 제공한다.

#### 한줄 요약

- OIDC/PKI 기반 워크로드 신원 인증, 1회성 동적 비밀 발급, 리스(Lease) 기반 자동 만료 및 감사 추적을 집행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정책 엔진(Policy Engine)**: 비밀 요청 주체의 IAM/AppRole 신원과 요청 자원 경로를 대조해 접근 허용 여부를 결정하는 중앙 통제 모듈이다.
- **비밀 엔진(Secrets Engine)**: RDBMS, K8s, AWS, PKI 등 개별 백엔드 시스템과 연동해 정적/동적 자격 증명을 실시간 생성 및 변환하는 모듈이다.
- **회전(Rotation)**: 정적 비밀(AWS Secrets Manager)이나 DB 비밀번호를 서비스 중단 없이 주기적(30일/90일)으로 자동 변경하는 처리 과정이다.
- **폐기(Revocation)**: 침해 발생 시 해당 리스(Lease) ID로 발급된 모든 계정 및 자격 증명을 대상 시스템에서 즉시 삭제 차단하는 응급 조치이다.
- **감사(Audit Log / Audit Trail)**: 모든 비밀 요청, 발급, 회전, 폐기 이벤트를 비가역 암호화해 SIEM으로 송신하는 기록 모듈이다.

</details>

```text
[워크로드 인증] ----- [정책 엔진] ----- [비밀 엔진]
                                             /     \
                              [리스·회전 관리]   [보호 저장·감사]
```

선의 의미: 워크로드 신원 인증, 정책 엔진 평가, 비밀 엔진 생성 흐름 및 리스/회전 통제와 암호화 감사 저장이 상호 연결된 비밀 관리 아키텍처이다.

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 인증 | OIDC, K8s Service Account, AWS IAM을 이용한 애플리케이션 무결성 인증 |
| 정책 엔진 | HCL/JSON 기반 **정책 엔진**으로 자원 접근 경로 및 CRUD 권한 통제 |
| 비밀 엔진 | **비밀 엔진**을 통해 DB(MySQL, PostgreSQL) 일회성 계정 생성 및 PKI 인증서 온디맨드 발급 |
| 리스·회전 관리 | **리스** 유효기간 관리, 람다 기반 **회전** 실행 및 침해 시 **폐기** 명령 전파 |
| 보호 저장·감사 | Storage Backend 내 AES-256 암호화 저장 및 **감사** 로그의 실시간 SIEM 전송 |

#### 한줄 요약

- 워크로드 인증, 정책 엔진의 권한 대조, 비밀 엔진의 실시간 동적 비밀 생성을 거쳐 리스 기반 회전 및 폐기를 실행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **단기 리스 자격(Short-lived Leased Credentials)**: 제한된 TTL과 Lease ID가 부여되어 지정된 시간 후에만 동작하는 임시 자격 증명이다.
- **긴급 폐기(Emergency Revocation)**: 비밀 유출 정황 탐지 시 Lease ID에 연결된 모든 동적 계정을 대상 DB/클라우드에서 즉각 지워버리는 강제 회수 단계이다.
- **실행 주체 신원 검증(Execution Identity Verification)**: 토큰을 제출한 컨테이너/VM의 고유 신원을 검증하는 단계이다.
- **대상•범위•수명 정책 판정(Target, Scope & TTL Policy Evaluation)**: 주체가 요청한 Secret Path 및 유효시간 TTL 정책을 대조하는 단계이다.
- **정책 범위 자격 생성(Policy-scoped Credential Generation)**: 비밀 엔진이 실제 DB에 임시 유저를 생성하는 단계이다.
- **단기 리스 자격 구성(Short-lived Leased Credential Assembly)**: 자격 증명에 TTL과 Lease ID를 부여해 워크로드에 반환하는 단계이다.
- **만료•긴급 폐기 판정(Expiration & Emergency Revocation Evaluation)**: TTL 만료 시점 또는 외부 긴급 명령 수신 시 자원 회수를 집행하는 단계이다.

</details>

```text
[워크로드] -- 신원 토큰 요청
      |
      v
[신원 제공자]
      |
      v
1. 실행 주체 신원 검증
      |
      `-- 검증 신원 토큰
                  |
                  v

      |
      v
2. 대상·범위·수명 정책 판정
      |
      `-- 동적 자격 생성 요청
                  |
                  v
[대상 시스템]
      |
      v
3. 정책 범위 자격 생성
      |
      `-- 생성 자격
             |
             v
[비밀 관리 체계]
      |
      v
4. 단기 리스 자격 구성
      |
      `-- 단기 리스 자격 ----> [워크로드 작업]
                                      |
                                      v
                             [대상 시스템 작업 결과]
                                      |
                                      v
+----------------------------------+
| 리스 만료·긴급 폐기              |
|                                  |
|  5. 만료·긴급 폐기 판정          |
|             |                    |
|             v                    |
|  대상 자격 폐기·감사 기록        |
+----------------------------------+
```

### 동작 원리

1. **실행 주체 신원 검증**: 워크로드가 제출한 OIDC/K8s 토큰을 기반으로 실행 주체의 무결성을 검증한다.
2. **대상•범위•수명 정책 판정**: 정책 엔진이 허용된 Secret 경로와 최대 TTL 수명을 확인 결정한다.
3. **정책 범위 자격 생성**: 비밀 엔진이 백엔드 DB/자원에 연결해 지정된 권한의 일회성 계정을 즉시 생성한다.
4. **단기 리스 자격 구성**: 생성된 자격에 Lease ID 및 TTL을 결합하여 애플리케이션으로 반환한다.
5. **만료•긴급 폐기 판정**: TTL 만료 시 자동으로 백엔드 자격 계정을 삭제하며, 이상징후 시 긴급 폐기를 수행한다.

#### 한줄 요약

- 신원 토큰 검증, 정책 대조, 실시간 임시 계정 생성, 단기 리스 구성 및 만료/긴급 폐기를 통한 자동 회수를 이행한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **고정 비밀(Static Secrets)**: 소스코드나 환경 변수(ENV)에 평문 또는 미회전 상태로 보관되는 전통적 비밀이다.
- **중앙 정적 비밀(Centralized Static Secrets)**: 중앙 보안 금고에 보관하되 유효기간이 길고 정기 회전에 의존하는 관리 방식이다.
- **Vault(HashiCorp Vault)**: 멀티 클라우드 동적 비밀(Dynamic Secrets) 생성 및 PKI 자동화에 특화된 오픈소스/엔터프라이즈 대표 솔루션이다.
- **아마존 웹 서비스 비밀 관리자(Amazon Web Services Secrets Manager, AWS Secrets Manager)**: AWS 환경 내 정적 비밀의 암호화 저장 및 람다(Lambda) 기반 자동 회전에 특화된 관리형 서비스이다.
- **데이터베이스(Database, DB)**: 동적 계정 생성의 주요 대상이 되는 RDBMS 및 NoSQL 시스템이다.

</details>

| 비밀 관리 방식 | 코드 하드코딩 (Static) | AWS Secrets Manager (Centralized Static) | HashiCorp Vault (Dynamic) |
|:---|:---|:---|:---|
| 핵심 개념 | 코드/파일에 비밀번호 직접 기재 | 중앙 암호화 저장 + 정기 회전(Rotation) | 요청 시 실시간 생성(Dynamic) + 리스(Lease) |
| 자격 증명 수명 | 무제한 (유출 시 치명적) | 설정된 회전 주기(예: 30일/90일) | 초/분 단위 단기 수명 (예: 1시간 TTL) |
| 백엔드 계정 생성 | 사전 작성된 고정 계정 공유 사용 | 사전 작성된 계정의 비밀번호 자동 회전 | 요청 시마다 일회성 유저/비밀번호 실시간 생성 |
| 장단점 및 한계 | 유출 위험 극대, 관리 불가 | 구축 용이, 동적 1회성 계정 생성 제약 | 최고 수준의 보안성 제공, 금고 가용성 운영 부담 |

#### 한줄 요약

- 하드코딩의 위험을 배제하고, 단순 저장소 중심인 AWS Secrets Manager와 실시간 생성 중심인 HashiCorp Vault를 목적에 맞게 혼용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-57**: 암호 키 및 자격 증명의 생성, 암호화, 저장, 회전, 폐기에 관한 키 관리 수명주기 국제 지침이다.
- **봉인 키(Unseal Key / Master Key)**: Vault 금고가 재부팅될 때 암호화된 마스터 키를 복원하기 위한 Shamir's Secret Sharing 기반의 분할 키 조각이다.
- **단계 회전(Phased Rotation / Dual-secret Rotation)**: 구 비밀번호와 신 비밀번호를 일정 시간 동시 허용하여 서비스 장애 없이 회전하는 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 자격 증명 수명주기 통제 미비 | **NIST SP 800-57** 규격 적용 | 암호 키 및 자격 증명의 국제 표준 수명주기 관리 체계 수립 |
| 금고 장애 시 마스터 키 복구 이슈 | Shamir's Secret Sharing 기반 **봉인 키** 분할 보관 | 3/5 인가자 동시 제출을 통한 안전한 금고 언실(Unseal) 가동 |
| 정적 비밀 회전 시 앱 연결 단절 | **단계 회전** (Dual-Secret Rotation) 스크립트 작성 | 서비스 다운타임 Zero 기반 비밀번호 자동 변경 보장 |

#### 한줄 요약

- NIST SP 800-57 가이드를 준수하고 봉인 키 분할 보관 및 무중단 단계 회전 스킴을 적용하여 가용성을 확보한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **최소 범위 자격(Least-scope Credentials)**: 필요한 최소한의 데이터 및 테이블만 접근 가능하도록 제한된 권한 객체이다.
- **최소 수명 자격(Least-time Credentials)**: 임무 수행 직후 소멸하도록 최단 시간 TTL이 부여된 일회성 자격 상태이다.

</details>

- **최소 범위 자격**과 **최소 수명 자격** 원칙을 실현하기 위해 동적 비밀 관리 체계(**Vault**, **AWS Secrets Manager**)를 구축 적용한다.

#### 한줄 요약

- 워크로드 신원 인증 기반 동적 비밀 발급, 리스 관제, 자동 회전 및 긴급 폐기 중심 비밀 관리 체계 구축 필수.
