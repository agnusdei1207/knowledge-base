## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비밀 관리 (Secrets Management)**: 데이터베이스 비밀번호, API 키, SSH 키, TLS 증명서 등 자격 증명의 전체 라이프사이클(저장, 발급, 회전, 폐기, 감사)을 암호화하여 중앙 통제하는 팩트 보안 체계이다.
- **하드코딩 비밀 (Hardcoded Secrets)**: 소스코드, Dockerfile, Git 저장소 내부에 비밀번호나 자격 증명을 평문으로 기재하여 포함시키는 심각한 보안 팩트 취약점 상태이다.

</details>

- 정의: 애플리케이션에 고정된 비밀번호를 하드코딩하는 방식을 배제하고, 워크로드 신원(Identity) 기반으로 단기 유효 자격 증명을 동적으로 발급 및 자동 회전시키는 중앙 팩트 통제 솔루션이다.
- 배경: 클라우드 파이프라인 확장에 따라 소스코드 내 하드코딩된 평문 자격 증명 및 장기 보관된 토큰이 해커의 직접적인 탈취 및 팩트 재사용 위험(Credential Reuse) 표적이 되었기 때문이다.

#### 한줄 요약

- 코드 하드코딩을 배제하고, 워크로드 신원 인증 기반으로 단기 유효 자격 증명을 팩트로 동적 발급 및 회전·폐기하는 중앙 통제 솔루션이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **워크로드 신원 (Workload Identity)**: K8s Service Account, AWS IAM Role, OIDC 토큰 등을 기반으로 클라우드 애플리케이션 및 마이크로서비스의 고유한 신원을 식별하는 팩트 기술이다.
- **부트스트랩 (Bootstrap)**: 신규 워크로드가 최초 기동 시 최초 인증용 신원 토큰(Vault AppRole 등)을 안전하게 수령받아 초기화하는 팩트 보안 절차이다.
- **OIDC (오픈아이디 커넥트 / OpenID Connect)**: OAuth 2.0 기반으로 워크로드 간 신원 정보를 토큰화하여 안전하게 상호 인증하는 범용 팩트 프로토콜이다.
- **PKI (공개키 기반구조 / Public Key Infrastructure)**: 비밀 관리 도구 내에서 동적 온디맨드 TLS/SSL 인증서를 자동 생성 및 발급하는 팩트 체계이다.
- **동적 비밀 (Dynamic Secrets)**: 워크로드의 자원 접근 요청 시점에 실시간으로 생성되고, 임무 종료 후 자동 소멸되는 일회성 단기 팩트 자격 증명이다.
- **리스 (Lease)**: 발급된 동적 비밀에 부여된 임대 유효기간이며, TTL 연장 또는 조기 폐기를 관제하는 암호학적 팩트 계약 단위이다.
- **TTL (유효 시간 / Time to Live)**: 동적 자격 증명이 실질적으로 작동할 수 있도록 제한된 팩트 수명 시간이다.

</details>

- **신원 기반 팩트 인증 연동**: **워크로드 신원**, **OIDC**, **PKI** 기반 부트스트랩을 연동하여 장기 고정 비밀번호 생성을 완전히 팩트로 배제한다.
- **일회성 동적 자격 발급**: 데이터베이스 요청 시마다 생성되는 **동적 비밀**과 극도로 짧은 **TTL**을 부여하여 탈취된 자격 증명의 팩트 악용 시간 창을 단축한다.
- **리스 기반 생애주기 관제**: **리스(Lease)** 시스템을 통해 발급 시점부터 자동 만료 및 긴급 폐기(Revocation)까지 100% 라이프사이클 감사 추적성을 팩트로 제공한다.

#### 한줄 요약

- OIDC/PKI 기반 워크로드 신원 인증, 일회성 동적 팩트 비밀 발급, 리스(Lease) 기반 자동 만료 및 감사 추적을 집행한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 엔진 (Policy Engine)**: 비밀 요청 주체의 IAM/AppRole 신원과 요청 자원 경로를 대조해 접근 허용 여부를 결정하는 중앙 통제 팩트 모듈이다.
- **비밀 엔진 (Secrets Engine)**: RDBMS, K8s, AWS, PKI 등 개별 백엔드 시스템과 연동해 정적/동적 자격 증명을 실시간 생성 및 변환하는 팩트 모듈이다.
- **회전 (Rotation)**: 정적 비밀(AWS Secrets Manager)이나 DB 비밀번호를 서비스 중단 없이 주기적(예: 30일/90일)으로 자동 변경하는 처리 팩트 과정이다.
- **폐기 (Revocation)**: 침해 정황 발생 시 해당 리스(Lease) ID로 발급된 모든 계정 및 자격 증명을 대상 시스템에서 즉시 팩트로 삭제 차단하는 응급 조치이다.

</details>

```text
[요청 워크로드 및 신원 인증] ----- [접근 권한 정책 엔진] ----- [백엔드 비밀 엔진]
                                                        /          \
                                  [리스 및 자동 회전 팩트 통제]   [AES-256 보호 저장 및 감사]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **워크로드 팩트 인증** | OIDC, K8s Service Account, AWS IAM을 이용한 애플리케이션 무결성 인증 | Authentication |
| **정책 엔진** | HCL/JSON 기반 정책 설정으로 요청 경로 및 CRUD 권한 팩트 통제 | Authorization |
| **비밀 엔진** | 대상 DB 일회성 계정 실시간 생성 및 PKI 인증서 온디맨드 팩트 발급 | Dynamic Gen |
| **리스 및 회전 관리** | 리스(Lease) 유효기간 관제, 무중단 팩트 **회전**, 침해 시 **폐기** 명령 전파 | Lifecycle |
| **보호 저장 및 감사** | 스토리지 내 AES-256 암호화 저장 및 **감사** 로그의 실시간 SIEM 전송 | Storage / Audit |

#### 한줄 요약

- 워크로드 팩트 인증, 정책 엔진 권한 대조, 비밀 엔진 실시간 동적 비밀 생성을 거쳐 리스 기반 회전 및 폐기를 실행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **단기 리스 자격 (Short-lived Leased Credentials)**: 제한된 TTL과 Lease ID가 부여되어 지정된 시간까지만 동작하는 임시 팩트 자격 증명이다.
- **긴급 폐기 (Emergency Revocation)**: 비밀 유출 정황 탐지 시 Lease ID에 연결된 모든 동적 계정을 대상 DB/클라우드에서 즉각 지워버리는 강제 회수 팩트 단계이다.

</details>

```text
[클라우드 워크로드] -- 팩트 신원 토큰 제출
      |
      v
[OIDC 신원 제공자]
      |
      v
1. 실행 주체 팩트 신원 검증
      |
      `-- 검증된 신원 토큰
                  |
                  v
[중앙 비밀 관리 플랫폼]
                  |
                  v
2. 요청 대상, 범위 및 TTL 정책 팩트 판정
                  |
                  `-- 동적 자격 생성 API 호출
                              |
                              v
[백엔드 대상 시스템 (DB 등)]
                              |
                              v
3. 정책 범위에 부합하는 일회성 유저 생성
                              |
                              `-- 생성된 임시 자격
                                          |
                                          v
[중앙 비밀 관리 플랫폼]
                                          |
                                          v
4. 단기 리스(Lease) 팩트 결속 및 구성
                                          |
                                          `-- 단기 리스 자격 발급 ----> [워크로드 작업 수행]
                                                                                  |
                                                                                  v
+------------------------------------------------+
| [리스 만료 또는 보안 침해 탐지 시]                 |
|                                                |
|  5. TTL 만료 및 긴급 폐기 팩트 판정 수행             |
|             |                                  |
|             v                                  |
|  백엔드 연동 자격 회수 파기 및 팩트 감사 기록 이행     |
+------------------------------------------------+
```

### 동작 원리

1. 신원 검증: 제출된 OIDC 및 K8s 토큰을 기반으로 실행 워크로드의 무결성을 팩트로 확인한다.
2. 정책 판정: 인가된 비밀 경로, 허용 범위, 유효시간(TTL) 정책을 대조한다.
3. 자격 생성: 비밀 엔진이 백엔드 DB 등에 접근 가능한 일회성 팩트 계정을 생성한다.
4. 리스 구성: 생성된 자격 증명에 Lease ID와 제한된 TTL을 팩트로 결속해 반환한다.
5. 폐기 통제: TTL 만료 또는 관제 시스템 이상 탐지 시 자격 증명을 즉각 팩트로 회수한다.

#### 한줄 요약

- 신원 토큰 팩트 검증, 정책 대조, 실시간 임시 계정 생성, 단기 리스 부여 및 만료 시 자동 파기 로직을 이행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고정 비밀 (Static Secrets)**: 소스코드나 환경 변수(ENV)에 평문 또는 미회전 상태로 영구적으로 보관되는 전통적 팩트 비밀이다.
- **중앙 정적 비밀 (Centralized Static Secrets)**: 중앙 보안 금고에 보관하되 유효기간이 길고 정기 회전에 의존하는 AWS Secrets Manager 같은 팩트 관리 방식이다.
- **HashiCorp Vault**: 멀티 클라우드 동적 비밀 생성 및 PKI 자동화에 특화된 엔터프라이즈 대표 팩트 솔루션이다.

</details>

| 팩트 비밀 관리 방식 | **코드 내 하드코딩 (Static)** | **AWS Secrets Manager (중앙 정적)** | **HashiCorp Vault (동적 비밀)** |
|:---|:---|:---|:---|
| 핵심 통제 개념 | 소스코드나 Dockerfile에 비밀번호를 직접 평문 기재 | 중앙 암호화 저장소 활용 및 정기적인 팩트 회전(Rotation) | 데이터 요청 시점 실시간 생성(Dynamic) 및 리스(Lease) 통제 |
| 자격 증명 수명 | **무제한 수명 (유출 시 치명적 보안 사고)** | 설정된 회전 주기 의존 (예: 30일 / 90일 수명) | **분·초 단위 단기 수명 보장 (예: 1시간 TTL)** |
| 백엔드 팩트 연동 | 고정된 단일 DB 계정을 다수 컨테이너가 공유 | 사전 작성된 고정 계정의 비밀번호를 자동 스크립트로 회전 | 요청마다 DB에 일회성 유저 및 비밀번호를 실시간 팩트 생성 |
| 한계점 | 팩트 기반 권한 통제 절대 불가 | 실시간 동적 계정 생성의 아키텍처 제약 존재 | 중앙 금고 시스템 가용성(HA) 유지보수 부담 존재 |

#### 한줄 요약

- 위험한 하드코딩을 배제하고, 단순 저장소 중심인 AWS Secrets Manager와 실시간 동적 생성 중심인 HashiCorp Vault를 목적에 맞게 팩트로 혼용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-57**: 암호 키 및 자격 증명의 생성, 암호화, 저장, 회전, 폐기에 관한 키 관리 수명주기 통제 국제 팩트 지침이다.
- **봉인 키 (Unseal Key)**: Vault 금고 서버 재부팅 시 암호화된 마스터 키를 복원하기 위한 Shamir's Secret Sharing 기반 분할 키 팩트 조각이다.
- **단계 회전 (Phased Rotation)**: 기존 구 비밀번호와 신 비밀번호를 일정 시간 동시 허용하여 DB 세션 끊김 등의 서비스 장애 없이 회전하는 팩트 기법이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| **수명주기 통제 누락으로 장기 탈취 방치** | 발급 후 폐기 정책이 없는 정적 비밀 구조 | **NIST SP 800-57** 규격 준용 기반 생애주기 관리 팩트 적용 | 국제 표준 부합 및 유출 자격 증명의 악용 시간 창 제거 |
| **금고 서버 재기동 시 마스터 키 복구 불가** | 마스터 키 단일 담당자 의존 및 키 유실 | Shamir's Secret Sharing 기반 **봉인 키 분할 보관 팩트 적용** | 3/5 인가자 동시 제출을 통한 금고(Vault) 언실(Unseal) 가용성 확보 |
| **정적 비밀 강제 회전 시 애플리케이션 연결 장애** | DB 비밀번호 변경 시 기존 세션 강제 종료 | 서비스 무중단을 보장하는 **단계 회전(Dual-Secret Rotation)** 적용 | 다운타임 제로(Zero) 기반의 안전한 비밀번호 자동 팩트 변경 보장 |

#### 한줄 요약

- NIST SP 800-57 가이드를 준수하고 봉인 키 분할 보관 및 무중단 단계 회전 스킴을 적용하여 팩트 가용성을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **최소 범위 자격 (Least-scope Credentials)**: 애플리케이션이 필요한 최소한의 데이터 및 테이블에만 팩트로 접근 가능하도록 제한된 권한 객체이다.
- **최소 수명 자격 (Least-time Credentials)**: 임무 수행 직후 즉시 소멸하도록 최단 시간 TTL이 부여된 일회성 팩트 자격 상태이다.

</details>

- **최소 범위 자격**과 **최소 수명 자격** 원칙의 무결한 실현을 위해, 워크로드 신원 기반 동적 비밀 관리 체계(**Vault**)와 클라우드 네이티브 정적 관리소(**AWS Secrets Manager**)를 결합한 암호 키 거버넌스 확립 필수이다.

#### 한줄 요약

- 단기 수명 동적 자격은 HashiCorp Vault, 클라우드 네이티브 정적 비밀은 AWS Secrets Manager를 입체 팩트 적용한다.
