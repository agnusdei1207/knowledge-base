## 미리 알고가기

- **비밀(Secret)**: 노출되면 접근에 악용될 수 있는 비밀번호·API 키·토큰·암호 키이다.
- **비밀 관리(Secrets Management)**: 비밀의 저장·인증·발급·회전·폐기·감사를 중앙 통제하는 체계이다.
- **정적 비밀(Static Secret)**: 관리자가 교체하기 전까지 같은 값을 사용하는 자격 증명이다.
- **동적 비밀(Dynamic Secret)**: 요청 시 생성되어 짧은 수명 뒤 자동 폐기되는 자격 증명이다.
- **워크로드 신원(Workload Identity)**: 응용·컨테이너·서버리스 함수 같은 실행 주체의 신원이다.
- **부트스트랩 비밀(Bootstrap Secret)**: 비밀 관리 체계에 최초 인증할 때 쓰는 초기 자격 증명이다.
- **리스(Lease)**: 동적 비밀의 유효시간(TTL)과 갱신·폐기 상태를 관리하는 계약이다.
- **회전(Rotation)**: 기존 비밀을 새 값으로 교체하고 사용처를 전환하는 절차이다.
- **폐기(Revocation)**: 비밀을 만료 전이라도 인증에 쓸 수 없게 만드는 처리이다.
- **공개키 기반구조(Public Key Infrastructure, PKI)**: 인증서와 공개키의 발급·배포·폐기를 관리하는 체계이다.
- **오픈아이디 커넥트(OpenID Connect, OIDC)**: OAuth 2.0 위에서 인증 결과를 표준 토큰으로 전달하는 계층이다.
- **Vault**: 정책 기반 비밀 저장과 동적 자격 발급을 제공하는 비밀 관리 제품이다.
- **AWS Secrets Manager**: AWS에서 비밀 저장·회전·접근 통제를 제공하는 관리형 서비스이다.
- **봉인 키(Seal Key)**: 비밀 저장소의 암호화 키를 보호하거나 잠금을 해제하는 핵심 키이다.
- **NIST SP 800-57 Part 1 Rev. 5**: 암호 키의 생성·저장·사용·폐기 수명주기를 제시하는 공식 지침이다.

## Ⅰ. 개요

- 정의/개념: 비밀의 저장·발급·회수를 통제하는 **보안 관리 체계**
- 배경/필요성: 하드코딩·장기 자격 탈취로 **접근 피해 장기화**

### 쉽게 이해하기 (학습용)

- 프로그램에 비밀번호를 넣지 않고 실행 주체의 신원을 확인하여 필요한 열쇠를 잠깐 빌려준 뒤 자동으로 거둔다.

## Ⅱ. 특징

- **초기 비밀 제거**: 워크로드 신원으로 부트스트랩 대체
- **노출 피해 제한**: 최소 권한·수명의 동적 비밀 발급
- **수명주기 추적**: 리스·회전·폐기·감사 사건 연결

### 쉽게 이해하기 (학습용)

- 중앙 금고에 보관하는 데 그치지 않고 누가 어떤 비밀을 얼마나 오래 쓰며 사용 뒤 실제 폐기되는지를 통제한다.

## Ⅲ. 구조 및 구성요소

```mermaid
block-beta
  columns 3
  A["워크로드 인증"]
  B["정책 엔진"]
  C["비밀 엔진"]
  D["리스·회전 관리"]
  E["보호 저장·감사"]
  A --- B
  B --- C
  C --- D
  D --- E
  E --- A
```

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 인증 | **OIDC·PKI 신원**으로 실행 주체 확인 |
| 정책 엔진 | **대상·작업 범위**와 수명 제한 |
| 비밀 엔진 | **정적 저장·동적 자격** 생성 |
| 리스·회전 관리 | **리스 관리·비밀 회전**으로 갱신·폐기 |
| 보호 저장·감사 | **암호화 보관·감사 사건** 기록 |

### 쉽게 이해하기 (학습용)

- 신원을 확인하고 정책에 맞는 비밀을 짧게 발급하며 수명이 끝나면 폐기하고 모든 사건을 보호된 기록에 남긴다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant W as 워크로드
    participant I as 신원 제공자
    participant S as 비밀 관리 체계
    participant T as 대상 시스템
    participant A as 감사 체계
    W->>I: 신원 토큰 요청
    I-->>W: 1. 검증 신원 토큰 발급
    W->>S: 2. 대상·범위·수명 전달
    S->>T: 3. 정책 범위 자격 생성
    T-->>S: 생성 자격 전달
    S-->>W: 4. 단기 리스 자격 발급
    W->>T: 제한 대상 작업 요청
    T-->>W: 작업 결과
    loop 리스 만료·긴급 폐기
        S->>T: 5. 대상 자격 폐기 요청
        S-->>A: 폐기·접근 감사 사건
    end
```

**동작 원리**

1. **검증 신원 토큰 발급**: 실행 환경·서비스 신원 검증
2. **대상·범위·수명 전달**: 자원·작업·TTL을 함께 요청
3. **정책 범위 자격 생성**: 대상 시스템에 단기 자격 생성
4. **단기 리스 자격 발급**: 자격·리스 식별자·TTL 전달
5. **대상 자격 폐기 요청**: 만료·긴급 회수 시 접근 차단


### 쉽게 이해하기 (학습용)

- 프로그램은 자기 신원을 증명해 작업 시간만 유효한 자격을 받고 시간이 끝나면 자격이 자동으로 무효화된다.

## Ⅴ. 종류 및 비교

| 비밀 관리 유형 | 고정 설정 | 중앙 정적 관리 | 동적 관리 |
|:---|:---|:---|:---|
| 적용 기준 | **격리 임시 개발** 환경 | **동적 발급 미지원** 대상 | **DB·클라우드 자동화** 대상 |
| 핵심 특징 | **코드·파일 장기 저장** | **금고의 정적 값 제공** | **요청별 단기 자격 생성** |
| 구현 예 | **환경 변수·설정 파일** | **AWS Secrets Manager** 정적 저장 | **Vault 동적 엔진**과 리스 |
| 한계 | **저장소·이미지 유출** | **회전 전파·캐시 지연** | **리스 서비스 가용성** 의존 |

### 쉽게 이해하기 (학습용)

- 고정 설정은 복제된 열쇠가 오래 남고 중앙 정적 관리는 보관을 개선하며 동적 관리는 작업마다 새 열쇠를 짧게 만든다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| **암호 키 수명 불일치**로 폐기 누락 | **NIST SP 800-57 키 관리** 적용 | **생성·보관·폐기 일관성** 확보 |
| **부트스트랩 비밀 노출**로 금고 접근 탈취 | **워크로드 신원·동적 발급** 적용 | **탈취 유효시간·범위** 축소 |
| **금고 장애·봉인 키 유실**로 발급 중단 | **다중화·키 분할 보관·복구훈련** | **비밀 서비스 연속성** 확보 |
| **정적 비밀 회전 실패**로 구·신값 충돌 | **AWS 자동 회전·단계 전환** 적용 | **서비스 중단 없는 교체** 지원 |

### 쉽게 이해하기 (학습용)

- 애플리케이션은 Vault에서 작업 수명만큼 유효한 개별 DB 계정을 받고 만료 시 자동 폐기하여 공유 비밀번호를 남기지 않는다.

## Ⅶ. 결론

- 자동 생성·폐기 대상은 **동적 비밀**, 미지원 레거시는 **중앙 정적 비밀·회전** 적용

### 쉽게 이해하기 (학습용)

- 비밀 관리의 목표는 안전한 저장소 자체가 아니라 올바른 워크로드에 최소 범위 자격을 짧게 발급하고 확실히 폐기하는 것이다.
