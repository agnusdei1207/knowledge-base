## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **비밀 관리**: 비밀번호•API 키•토큰•암호 키의 저장•인증•발급•회전•폐기•감사를 중앙 통제하는 체계이다.
- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 서비스 기능과 데이터를 정해진 형식으로 제공하는 경계
- **하드코딩 비밀**: 소스•설정•이미지에 장기 자격을 직접 넣어 복제와 유출 뒤 피해가 지속되는 상태이다.

</details>

- 정의/개념: 비밀의 저장•발급•회전•폐기를 통제하는 **자격정보 관리 체계**
- 배경/필요성: 하드코딩•장기 자격 탈취로 **접근 피해 장기화**

#### 한줄 요약

- 프로그램에 비밀번호를 넣지 않고 실행 주체의 신원을 확인하여 필요한 열쇠를 잠깐 빌려준 뒤 자동으로 거둔다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **워크로드 신원** 은 실행 중인 서비스•프로세스•장치를 식별하고 인증하는 디지털 신원이다.
- **부트스트랩** 은 워크로드가 비밀 관리 체계에 처음 신뢰를 설정하는 초기 인증 절차다.
- **오픈아이디 커넥트(OpenID Connect, OIDC)**: 사용자나 워크로드의 인증 결과와 신원 정보를 전달하는 프로토콜
- **공개키 기반구조(Public Key Infrastructure, PKI)**: 공개키 인증서의 발급•검증•폐기를 관리하는 신뢰 체계
- **동적 비밀** 은 요청할 때 대상 시스템에 새로 생성하는 짧은 수명의 자격 정보다.
- **리스** 는 발급한 비밀의 유효기간•갱신•폐기 상태를 관리하는 계약이다.
- **유효 시간(Time to Live, TTL)**: 비밀이나 리스가 만료되기 전까지 유효한 시간

</details>

- **초기 비밀 제거**: 워크로드 신원으로 부트스트랩 대체
- **노출 피해 제한**: 최소 권한•수명의 동적 비밀 발급
- **수명주기 추적**: 리스•회전•폐기•감사 사건 연결

#### 한줄 요약

- 중앙 금고에 보관하는 데 그치지 않고 누가 어떤 비밀을 얼마나 오래 쓰며 사용 뒤 실제 폐기되는지를 통제한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정책 엔진** 은 비밀을 사용할 대상•작업•수명 범위를 제한한다.
- **비밀 엔진** 은 정적 비밀을 제공하거나 대상 시스템에 동적 자격을 생성한다.
- **회전** 은 기존 비밀을 새 값으로 교체하고 사용처를 전환하는 처리다.
- **폐기** 는 유효기간 전이라도 비밀과 대상 자격을 즉시 무효화하는 처리다.
- **감사** 는 비밀의 접근•발급•갱신•폐기 사건을 추적 가능하게 기록하는 활동이다.

</details>

```text
[워크로드 인증] ----- [정책 엔진] ----- [비밀 엔진]
                                             /     \
                              [리스•회전 관리]   [보호 저장•감사]
```

선의 의미: 가로선은 워크로드 신원, 사용 정책과 비밀 생성 기능의 정적 접근 경계이고, 비밀 엔진 아래에는 자격 수명을 통제하는 리스•회전 관리와 암호화 보관•감사를 담당하는 보호 저장•감사가 분리된다.

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 인증 | **OIDC•PKI 신원** 으로 실행 주체 확인 |
| 정책 엔진 | **대상•작업 범위** 와 수명 제한 |
| 비밀 엔진 | **정적 저장•동적 자격** 생성 |
| 리스•회전 관리 | **리스 관리•비밀 회전** 으로 갱신•폐기 |
| 보호 저장•감사 | **암호화 보관•감사 사건** 기록 |

#### 한줄 요약

- 신원을 확인하고 정책에 맞는 비밀을 짧게 발급하며 수명이 끝나면 폐기하고 모든 사건을 보호된 기록에 남긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **단기 리스 자격**: 대상 시스템에 생성한 최소 권한 자격에 리스 식별자와 TTL을 결합해 워크로드에 제공하는 증명 정보이다.
- **긴급 폐기**: 유출이나 위험 변화가 확인되면 유효기간이 남아 있어도 대상 시스템의 자격을 즉시 무효화하는 처리이다.

</details>

```text
[워크로드] -- 신원 토큰 요청
      |
      v
[신원 제공자]
      |
      v
1. 실행 주체 신원 검증
      |
      `-- 검증 신원 토큰
                  |
                  v
[비밀 관리 체계]
      |
      v
2. 대상•범위•수명 정책 판정
      |
      `-- 동적 자격 생성 요청
                  |
                  v
[대상 시스템]
      |
      v
3. 정책 범위 자격 생성
      |
      `-- 생성 자격
             |
             v
[비밀 관리 체계]
      |
      v
4. 단기 리스 자격 구성
      |
      `-- 단기 리스 자격 ----> [워크로드 작업]
                                      |
                                      v
                             [대상 시스템 작업 결과]
                                      |
                                      v
+----------------------------------+
| 리스 만료•긴급 폐기              |
|                                  |
|  5. 만료•긴급 폐기 판정          |
|             |                    |
|             v                    |
|  대상 자격 폐기•감사 기록        |
+----------------------------------+
```

**동작 원리**

1. **실행 주체 신원 검증**: 실행 환경•서비스 신원 확인
2. **대상•범위•수명 정책 판정**: 자원•작업•TTL 허용 여부 결정
3. **정책 범위 자격 생성**: 대상 시스템에서 최소 권한 자격 발급
4. **단기 리스 자격 구성**: 자격•리스 식별자•TTL 결합
5. **만료•긴급 폐기 판정**: TTL•유출•위험 변화로 회수 결정


#### 한줄 요약

- 프로그램은 자기 신원을 증명해 작업 시간만 유효한 자격을 받고 시간이 끝나면 자격이 자동으로 무효화된다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **고정 비밀** 은 소스•설정•환경 변수에 장기 저장하는 자격 정보다.
- **중앙 정적 비밀** 은 중앙 금고가 보관하고 승인된 주체에게 제공하는 고정 자격 정보다.
- **Vault** 는 동적 비밀 엔진과 리스 기반 자격 발급을 제공하는 비밀 관리 도구다.
- **아마존 웹 서비스 비밀 관리자(Amazon Web Services Secrets Manager, AWS Secrets Manager)**: 정적 비밀 저장과 자동 회전을 제공하는 관리형 서비스
- **데이터베이스(Database, DB)**: 구조화된 데이터를 저장•질의하는 시스템

</details>

| 비밀 관리 유형 | 고정 설정 | 중앙 정적 관리 | 동적 관리 |
|:---|:---|:---|:---|
| 적용 기준 | **격리 임시 개발** 환경 | **동적 발급 미지원** 대상 | **DB•클라우드 자동화** 대상 |
| 핵심 특징 | **코드•파일 장기 저장** | **금고의 정적 값 제공** | **요청별 단기 자격 생성** |
| 구현 예 | **환경 변수•설정 파일** | **AWS Secrets Manager** 정적 저장 | **Vault 동적 엔진** 과 리스 |
| 한계 | **저장소•이미지 유출** | **회전 전파•캐시 지연** | **리스 서비스 가용성** 의존 |

#### 한줄 요약

- 고정 설정은 복제된 열쇠가 오래 남고 중앙 정적 관리는 보관을 개선하며 동적 관리는 작업마다 새 열쇠를 짧게 만든다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST(National Institute of Standards and Technology)** 는 미국의 기술 표준과 지침을 개발하는 기관이다.
- **SP(Special Publication) 800-57** 은 암호 키의 생성•저장•사용•회전•폐기 수명주기를 제시한다.
- **봉인 키** 는 비밀 금고의 저장 데이터를 암호화하는 최상위 보호 키다.
- **단계 회전** 은 구•신 비밀의 사용처를 순차 전환해 중단 없이 교체하는 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **암호 키 수명 불일치** 로 폐기 누락 | **NIST SP 800-57 키 관리** 적용 | **생성•보관•폐기 일관성** 확보 |
| **부트스트랩 비밀 노출** 로 금고 접근 탈취 | **워크로드 신원•동적 발급** 적용 | **탈취 유효시간•범위** 축소 |
| **금고 장애•봉인 키 유실** 로 발급 중단 | **다중화•키 분할 보관•복구훈련** | **비밀 서비스 연속성** 확보 |
| **정적 비밀 회전 실패** 로 구•신값 충돌 | **AWS 자동 회전•단계 전환** 적용 | **서비스 중단 없는 교체** 지원 |

#### 한줄 요약

- 애플리케이션은 Vault에서 작업 수명만큼 유효한 개별 DB 계정을 받고 만료 시 자동 폐기하여 공유 비밀번호를 남기지 않는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **최소 범위 자격** 은 필요한 대상과 작업만 수행할 수 있도록 권한을 제한한 비밀이다.
- **최소 수명 자격** 은 작업에 필요한 짧은 시간만 유효하고 사용 뒤 폐기되는 비밀이다.

</details>

- 자동 생성•폐기 대상은 **동적 비밀**, 미지원 레거시는 **중앙 정적 비밀•회전** 적용

#### 한줄 요약

- 비밀 관리의 목표는 안전한 저장소 자체가 아니라 올바른 워크로드에 최소 범위 자격을 짧게 발급하고 확실히 폐기하는 것이다.
