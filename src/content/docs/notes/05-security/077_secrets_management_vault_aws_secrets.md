## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **비밀 관리(Secrets Management)**: 비밀번호•API 키•토큰•암호 키의 저장•인증•발급•회전•폐기•감사를 중앙 통제하는 보안 체계.
- **애플리케이션 프로그래밍 인터페이스(Application Programming Interface, API)**: 서비스 기능과 데이터를 정해진 형식으로 제공하는 인터페이스.
- **하드코딩 비밀(Hardcoded Secrets)**: 소스•설정•이미지에 장기 자격을 직접 넣어 복제와 유출 뒤 피해가 지속되는 보안 취약 상태 지칭.

</details>

- 정의/개념: API 키•토큰•암호 키의 저장•발급•회전•폐기를 중앙 통제하는 보안 체계
- 배경/필요성: 하드코딩 비밀 및 장기 자격 유출에 따른 보안 사고 위험 차단 필요

#### 한줄 요약

- 코드에 시크릿을 하드코딩하지 않고 실행 주체의 신원을 인증하여 필요한 자격 증명을 단기 발급한 뒤 자동으로 폐기한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **워크로드 신원(Workload Identity)**: 실행 중인 서비스•프로세스•장치를 식별하고 인증하는 디지털 신원.
- **부트스트랩(Bootstrap)**: 워크로드가 비밀 관리 체계에 처음 신뢰를 설정하는 초기 인증 절차.
- **오픈아이디 커넥트(OpenID Connect, OIDC)**: 사용자나 워크로드의 인증 결과와 신원 정보를 전달하는 인증 프로토콜.
- **공개키 기반구조(Public Key Infrastructure, PKI)**: 공개키 인증서의 발급•검증•폐기를 관리하는 신뢰 기반구조 지칭.
- **동적 비밀(Dynamic Secrets)**: 요청할 때 대상 시스템에 새로 생성하는 짧은 수명의 자격 정보에 해당함.
- **리스(Lease)**: 발급한 비밀의 유효기간•갱신•폐기 상태를 관리하는 계약 메커니즘.
- **유효 시간(Time to Live, TTL)**: 비밀이나 리스가 만료되기 전까지 유지되는 유효 기간.

</details>

- **워크로드 신원**과 **OIDC**•**PKI** 기반 **부트스트랩** 장기 비밀 대체
- 최소 권한 및 짧은 **TTL** 기반 **동적 비밀** 발급
- **리스** 메커니즘을 통한 발급•갱신•폐기•감사 사건 결합

#### 한줄 요약

- 중앙 금고에 보관하는 데 그치지 않고 누가 어떤 비밀을 얼마나 오래 쓰며 사용 뒤 실제 폐기되는지를 통제한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정책 엔진(Policy Engine)**: 비밀을 사용할 대상•작업•수명 범위를 제한하는 통제 기능.
- **비밀 엔진(Secrets Engine)**: 정적 비밀을 제공하거나 대상 시스템에 동적 자격을 생성하는 엔진 모듈.
- **회전(Rotation)**: 기존 비밀을 새 값으로 교체하고 사용처를 전환하는 주기적 교체 처리.
- **폐기(Revocation)**: 유효기간 전이라도 비밀과 대상 자격을 즉시 무효화하는 처리 방식.
- **감사(Audit)**: 비밀의 접근•발급•갱신•폐기 사건을 추적 가능하게 기록하는 활동.

</details>

```text
[워크로드 인증] ----- [정책 엔진] ----- [비밀 엔진]
                                             /     \
                              [리스•회전 관리]   [보호 저장•감사]
```

선 의미: 가로선은 워크로드 신원, 사용 정책과 비밀 생성 기능의 정적 접근 경계 표현이며, 하단은 자격 수명을 통제하는 리스•회전 관리 및 보호 저장•감사 분리 구조 지칭

| 구성요소 | 책임 |
|:---|:---|
| 워크로드 인증 | OIDC•PKI 신원으로 실행 주체 확인 |
| 정책 엔진 | **정책 엔진**이 대상•작업•수명 제한 |
| 비밀 엔진 | **비밀 엔진**이 정적•동적 자격 생성 |
| 리스•회전 관리 | **리스**•**회전**으로 갱신 및 **폐기**로 즉시 무효화 |
| 보호 저장•감사 | 암호화 보관 및 **감사** 사건 기록 |

#### 한줄 요약

- 신원을 확인하고 정책에 맞는 비밀을 짧게 발급하며 수명이 끝나면 폐기하고 모든 사건을 보호된 기록에 남긴다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **단기 리스 자격(Short-lived Leased Credentials)**: 대상 시스템에 생성한 최소 권한 자격에 리스 식별자와 TTL을 결합해 워크로드에 제공하는 자격 정보.
- **긴급 폐기(Emergency Revocation)**: 유출이나 위험 변화 확인 시 유효기간에 관계없이 대상 자격을 즉시 무효화하는 예외 처리.
- **실행 주체 신원 검증(Execution Identity Verification)**: 실행 환경•서비스가 등록된 워크로드인지 확인하는 단계.
- **대상•범위•수명 정책 판정(Target, Scope & TTL Policy Evaluation)**: 요청 자원•작업•TTL이 허용 범위인지 결정하는 단계.
- **정책 범위 자격 생성(Policy-scoped Credential Generation)**: 대상 시스템에서 최소 권한의 단기 자격을 만드는 단계.
- **단기 리스 자격 구성(Short-lived Leased Credential Assembly)**: 생성한 자격에 리스 식별자와 TTL을 결합하는 단계.
- **만료•긴급 폐기 판정(Expiration & Emergency Revocation Evaluation)**: TTL 만료•유출•위험 변화에 따라 자격 회수 여부를 결정하는 단계.

</details>

```text
[워크로드] -- 신원 토큰 요청
      |
      v
[신원 제공자]
      |
      v
1. 실행 주체 신원 검증
      |
      `-- 검증 신원 토큰
                  |
                  v
[비밀 관리 체계]
      |
      v
2. 대상•범위•수명 정책 판정
      |
      `-- 동적 자격 생성 요청
                  |
                  v
[대상 시스템]
      |
      v
3. 정책 범위 자격 생성
      |
      `-- 생성 자격
             |
             v
[비밀 관리 체계]
      |
      v
4. 단기 리스 자격 구성
      |
      `-- 단기 리스 자격 ----> [워크로드 작업]
                                      |
                                      v
                             [대상 시스템 작업 결과]
                                      |
                                      v
+----------------------------------+
| 리스 만료•긴급 폐기              |
|                                  |
|  5. 만료•긴급 폐기 판정          |
|             |                    |
|             v                    |
|  대상 자격 폐기•감사 기록        |
+----------------------------------+
```

### 동작 원리

1. **실행 주체 신원 검증**: 실행 환경•서비스에 대한 실행 주체 신원 검증 수행
2. **대상•범위•수명 정책 판정**: 자원•작업•TTL 기준 대상•범위•수명 정책 판정
3. **정책 범위 자격 생성**: 대상 시스템 내 정책 범위 자격 생성 집행
4. **단기 리스 자격 구성**: 자격•리스 식별자•TTL 기반 **단기 리스 자격** 구성
5. **만료•긴급 폐기 판정**: TTL 만료•유출•위험 변화 시 만료•긴급 폐기 판정

#### 한줄 요약

- 프로그램은 자기 신원을 증명해 작업 시간만 유효한 자격을 받고 필요하면 긴급 폐기한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **고정 비밀(Static Secrets)**: 소스•설정•환경 변수에 장기 저장하는 자격 정보 지칭.
- **중앙 정적 비밀(Centralized Static Secrets)**: 중앙 금고가 보관하고 승인된 주체에게 제공하는 정적 자격 정보.
- **Vault(HashiCorp Vault)**: 동적 비밀 엔진과 리스 기반 자격 발급을 제공하는 비밀 관리 도구.
- **아마존 웹 서비스 비밀 관리자(Amazon Web Services Secrets Manager, AWS Secrets Manager)**: 정적 비밀 저장과 자동 회전을 제공하는 관리형 클라우드 서비스.
- **데이터베이스(Database, DB)**: 구조화된 데이터를 저장•질의하는 데이터 관리 시스템.

</details>

| 비밀 관리 유형 | 고정 설정 | 중앙 정적 관리 | 동적 관리 |
|:---|:---|:---|:---|
| 적용 기준 | 격리 임시 개발 환경 | 동적 발급 미지원 대상 | **DB**•클라우드 자동화 대상 |
| 핵심 특징 | **고정 비밀**의 코드•파일 저장 | **중앙 정적 비밀**의 금고 제공 | **동적 비밀**의 요청별 생성 |
| 구현 예 | 환경 변수•설정 파일 | **AWS Secrets Manager** 정적 저장 | **Vault** 동적 엔진•리스 |
| 한계 | 저장소•이미지 유출 | 회전 전파•캐시 지연 | 리스 서비스 가용성 의존 |

#### 한줄 요약

- 하드코딩 방식은 유출된 자격 증명이 오래 잔존하고 중앙 정적 관리는 저장 보안을 개선하며 동적 관리는 요청마다 단기 자격 증명을 발급한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-57(NIST Recommendation for Key Management, SP 800-57)**: 암호 키의 생성•저장•사용•회전•폐기 수명주기를 제시하는 미국 국립표준기술연구소 지침.
- **봉인 키(Unseal Key)**: 비밀 금고의 저장 데이터를 암호화하는 최상위 보호 키.
- **단계 회전(Phased Rotation)**: 구•신 비밀의 사용처를 순차 전환해 중단 없이 교체하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 암호 키 수명 불일치로 폐기 누락 | **NIST SP 800-57** 적용 | 생성•보관•폐기 일관성 확보 |
| 부트스트랩 비밀 노출로 금고 접근 탈취 | **워크로드 신원**•동적 발급 적용 | 탈취 유효시간•범위 축소 |
| 금고 장애•봉인 키 유실로 발급 중단 | 다중화•**봉인 키** 분할 보관•복구훈련 | 비밀 서비스 연속성 확보 |
| 정적 비밀 회전 실패로 구•신값 충돌 | AWS 자동 회전•**단계 회전** 적용 | 서비스 중단 없는 교체 지원 |

#### 한줄 요약

- 애플리케이션은 Vault에서 작업 수명만큼 유효한 개별 DB 계정을 받고 만료 시 자동 폐기하여 공유 비밀번호를 남기지 않는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **최소 범위 자격(Least-scope Credentials)**: 필요한 대상과 작업만 수행할 수 있도록 권한을 제한한 자격 정보.
- **최소 수명 자격(Least-time Credentials)**: 작업에 필요한 짧은 시간만 유효하고 사용 뒤 폐기되는 자격 정보 지칭.

</details>

- **최소 범위 자격**과 **최소 수명 자격** 원칙 기반 **동적 비밀** 적용 및 미지원 대상 **중앙 정적 비밀**•**회전** 연계

#### 한줄 요약

- 비밀 관리의 목표는 안전한 저장소 자체가 아니라 올바른 워크로드에 최소 범위 자격을 짧게 발급하고 확실히 폐기하는 것이다.
