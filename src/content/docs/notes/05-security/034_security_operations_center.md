## 미리 알고가기

- **보안 운영 센터(Security Operations Center, SOC)**: 사람·절차·기술을 통합하여 보안 이벤트를 상시 탐지·분석·대응하는 조직
- **보안 정보 및 이벤트 관리(Security Information and Event Management, SIEM)**: 여러 보안 로그를 정규화·상관분석하여 경보와 조사 근거를 생성하는 시스템
- **보안 오케스트레이션·자동화·대응(Security Orchestration, Automation and Response, SOAR)**: 보안 도구를 연계하여 사건 조사·승인·조치 절차를 자동화하는 플랫폼
- **종단 탐지·대응(Endpoint Detection and Response, EDR)**: 단말의 행위를 수집·분석하여 위협 프로세스를 탐지·격리하는 기술
- **네트워크 탐지·대응(Network Detection and Response, NDR)**: 네트워크 트래픽과 행위를 분석하여 위협 통신을 탐지·대응하는 기술
- **사이버 위협 인텔리전스(Cyber Threat Intelligence, CTI)**: 탐지 규칙과 위협 헌팅에 공격자·전술·지표의 맥락을 제공하는 정보
- **에스컬레이션(Escalation)**: 분석가의 권한이나 역량을 넘는 보안 사건을 상위 책임자나 전문 대응팀으로 신속히 이관하는 절차이다.




## Ⅰ. 개요

- 정의: 사람·절차·기술을 통합한 **보안 운영 조직**
- 기존 한계: 분산 경보의 **책임·대응 단절**

### 쉽게 이해하기 (학습용)

- 탐지·대응을 위해 인력·절차·기술 통합

## Ⅱ. 특징

- 24시간 **탐지·분석·대응 운영**
- 역할·승인·에스컬레이션의 **책임 체계**
- SIEM·SOAR·EDR 기반 **통합 관제**

### 쉽게 이해하기 (학습용)

- 격리 및 복구 주체·권한 정의 필수

## Ⅲ. 구성요소 및 구조

```text
[거버넌스]
  ├─ [데이터 운영]
  ├─ [탐지 공학]
  └─ [사고 대응]
        ↓
[지식 관리]
```

| 설계 요소 | 설명 |
|:---|:---|
| 서비스·거버넌스 | 범위·역할·승인·성과 정의 |
| 데이터 운영 | 자산·네트워크 가시성 확보 |
| 탐지 공학 | 위협 분석·탐지 공백 제거 |
| 사고 대응 | 사건 분석·조치·복구 |
| 자동화·지식 | 반복 절차·지식 표준화 |

> 요약: SOC가 데이터·대응 주체를 사건 단위로 연결함

### 쉽게 이해하기 (학습용)

- 조직 내 유관 부서와의 유기적 연결

## Ⅳ. 원리 및 절차 흐름도

```text
임무설계
  ↓
로그수집
  ↓
대응준비
  ↓
관제대응
  ↓
훈련개선
```

| 절차 | 설명 |
|:---|:---|
| 임무설계 | 범위·책임 수준 정의함 |
| 로그수집 | 가시성 확보함 |
| 대응준비 | 플레이북 설계함 |
| 관제대응 | 격리·보고 수행함 |
| 훈련개선 | 공백 보완함 |

> 요약: 임무 설계 후 로그 수집·대응 준비·운영함

### 쉽게 이해하기 (학습용)

- 훈련을 통한 운영 실효성 검증

## Ⅴ. 종류 및 비교

| SOC 운영 모델 | 내부 SOC | 공동 SOC | 외부 위탁 |
|:---|:---|:---|:---|
| 적용 기준 | 자산 문맥·직접 조치 권한이 중요할 때 | 내부 책임과 외부 전문성을 결합할 때 | 상시 인력·기술 확보가 어려울 때 |
| 핵심 특징 | 내부 인력의 직접 탐지·대응 | 내부·외부 역할 분담 | 외부 전문 조직 관제 |
| 한계 | 인력 부족·교대 피로 | 책임·인계 경계 모호 | 자산 맥락·조치 권한 부족 |

> 요약: 모델은 문맥·전문성·조치 권한으로 결정함

### 쉽게 이해하기 (학습용)

- 대응 권한 부재 시 운영 효과 저하

## Ⅵ. 실무 사례

1. 피싱 경보의 **분석·격리·복구를 SOC에서 통합 수행**

### 쉽게 이해하기 (학습용)

- SOC는 피싱 신고를 접수하면 메일·단말·계정 로그를 함께 조사하고 악성 메일 격리와 탈취 계정 복구까지 추적한다.

## Ⅶ. 결론

- 단편적인 보안 장비 운영을 극복하기 위해 자산 중요도·탐지 정확도·조치 권한·복구 책임을 검토하여, 사고 전 과정을 책임지는 SOC 운영 모델을 선택해야 한다.

### 쉽게 이해하기 (학습용)

- 중요한 침해를 끝까지 복구하는 운영 체계
