## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 애플리케이션 간 기능과 데이터를 정해진 규칙에 따라 상호작용하는 경계 인터페이스.
- **보안 API 설계(Secure API Design)**: 요청의 채널, 토큰, 객체 권한 및 자원 사용을 매 호출마다 독립적으로 검증하는 응용 보안 설계 기법.

</details>

- 정의/개념: **API** 요청 채널, 토큰, 객체 권한 및 자원 소비에 대한 매 요청별 독립 검증 수행.
- 배경/필요성: 단순 호출자 인증 기반 접근 제어의 개별 객체 보호 및 과도한 자원 소비 통제 한계 극복.

#### 한줄 요약

- 보안 API는 호출자 인증만으로 끝내지 않고 매 요청의 객체•행위 권한과 자원 소비를 제한해야 한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **접근 토큰(Access Token)**: 보호 대상 자원에 대한 제한된 접근 권한을 증명하는 자격 증명 데이터.
- **범위(Scope)**: 접근 토큰을 통해 허용되는 대상 자원과 수행 가능한 행위의 경계를 지정하는 정책 값.
- **객체 인가(Object-Level Authorization)**: 요청 주체가 특정 자원 인스턴스에 접근할 권한이 있는지 검증하는 통제 메커니즘.
- **기능 인가(Function-Level Authorization)**: 요청 주체가 특정 업무 기능 및 API 엔드포인트를 실행할 권한이 있는지 확인하는 통제 방식.
- **호출률 제한(Rate Limiting)**: 일정 시간 동안 동일 주체의 API 요청 횟수를 제한하여 서비스 과부하를 방지하는 통제 기법.

</details>

- 호출자 인증과 **객체 인가**•**기능 인가**의 요청 단위 분리 집행.
- **접근 토큰**의 발급자, 대상, **범위**, 만료시간 및 채널 결속 상태 검증.
- 요청 크기 제한 및 **호출률 제한**을 통한 서비스 자원 남용 방지.

#### 한줄 요약

- 짧고 제한된 토큰, 객체 수준 권한 검사, 호출률 제한을 결합해 자격 탈취와 대량 남용의 영향을 줄인다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **API 게이트웨이(API Gateway)**: 클라이언트 요청의 인증•인가•라우팅•호출률 제한을 단일 접점에서 일괄 처리하는 중앙 진입점.
- **인증•권한 서버(Authentication & Authorization Server)**: 사용자 및 클라이언트 신원을 검증하고 권한 범위를 명시한 접근 토큰을 발급하는 시스템.
- **자원 서버(Resource Server)**: 클라이언트의 접근 토큰 및 세부 객체•기능 권한을 검증하여 보호된 자원을 제공하는 서버.

</details>

```text
보안 API 구조
├─ 등록 클라이언트: 호출 주체 식별
├─ 인증•권한 서버: 접근 토큰 발급
├─ API 게이트웨이: 토큰•채널•호출률 검증
├─ 자원 서버: 객체•기능 권한 집행
└─ 키•인증서•감사: 신뢰 수명•이력 관리
```

| 구성요소 | 책임 |
|:---|:---|
| 등록 클라이언트 | 호출 주체•접속 정보 식별 |
| 인증•권한 서버 | **인증•권한 서버**가 접근 토큰 발급 |
| API 게이트웨이 | **API 게이트웨이**가 토큰•채널•호출률 검증 |
| 자원 서버 | **자원 서버**가 객체•기능 권한 집행 |
| 키•인증서•감사 | 신뢰 수명•호출 이력 관리 |

#### 한줄 요약

- 게이트웨이가 공통 검사를 수행하고 서비스가 업무 객체의 권한을 다시 확인하며 로그가 두 판정을 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **자바스크립트 객체 표기법(JavaScript Object Notation, JSON)**: 속성-값 쌍 또는 배열 형태로 데이터를 구조화하여 교환하는 경량 데이터 포맷.
- **JSON 웹 토큰(JSON Web Token, JWT)**: 당사자 간의 주장을 안전하게 전송하기 위해 JSON 객체로 서명된 표준 토큰 규격.
- **상호 전송 계층 보안(Mutual Transport Layer Security, mTLS)**: 클라이언트와 서버가 서로의 디지털 서명 인증서를 상호 검증하는 암호화 통신 채널 기술.
- **mTLS•접근 토큰 검증(mTLS & Access Token Validation)**: 통신 채널과 접근 토큰의 서명•발급자•대상•만료일을 종합 확인하는 단계.
- **입력 크기•호출률 통제(Input Size & Rate Limit Control)**: 요청 데이터 크기와 단위 시간당 호출 횟수를 제한하여 자원 남용을 방지하는 통제.
- **객체 소유권 검증(Object Ownership Verification)**: 요청 주체가 접근하려는 대상 자원 인스턴스의 실제 소유자 또는 허용 대상인지 판정하는 절차.
- **기능•범위 인가(Function & Scope Authorization)**: 요청한 기능과 접근 토큰에 정의된 scope 권한 범위를 대조 검증하는 단계.
- **호출•인가 판정 기록(Call & Authorization Decision Logging)**: 요청 주체, 대상 객체, 승인•거부 결과 및 판단 근거를 감사 이력으로 보존하는 과정.

</details>

```text
JWT 접근 토큰•API 요청
          |
          v
1. mTLS•접근 토큰 검증
          |
          v
2. 입력 크기•호출률 통제
          |
          v
3. 객체 소유권 검증
          |
          v
4. 기능•범위 인가
          |
          +-- 거부 -- 오류•감사 기록
          |
          +-- 허용 -- 5. 호출•인가 판정 기록
                              |
                              v
                          제한된 API 응답
```

### 동작 원리

1. **mTLS•접근 토큰 검증**: 채널 상호 인증 및 토큰 발급자•대상•만료•서명 상태 검증 완료.
2. **입력 크기•호출률 통제**: 주체별 자원 소비량 및 요청 계약 기준 입력 크기•호출률 통제 적용.
3. **객체 소유권 검증**: 요청 주체의 대상 자원 인스턴스 접근 권한을 객체 소유권 검증으로 확인.
4. **기능•범위 인가**: 요청 행위와 토큰 허용 scope 범위를 대조하여 기능•범위 인가 수행.
5. **호출•인가 판정 기록**: 주체, 객체, 판정 결과 및 승인 근거를 호출•인가 판정 기록으로 보존.


#### 한줄 요약

- **JWT**의 발급자•대상•기한을 확인하고 **JSON** 요청 객체에 대한 호출자의 권한을 검증한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **개방형 권한 위임(Open Authorization, OAuth) 2.0**: 사용자 비밀번호 노출 없이 제3자 애플리케이션에 제한된 리소스 접근 권한을 위임하는 오픈 표준 프레임워크.
- **코드 교환용 증명 키(Proof Key for Code Exchange, PKCE)**: 인가 코드 탈취 공격을 방지하기 위해 일회성 검증 코드를 추가하는 OAuth 2.0 보안 확장 규격.

</details>

| 통제 지점 | 대표 수단 | 역할•잔여 위험 |
|:---|:---|:---|
| API 호출 경계 | 계층형 인증•인가•입력 검증 | 전체 경로를 보호하되 계층 간 정책 일치 필요 |
| 주장 전달 | **JWT** | 서명 주장을 전달하되 탈취•검증 오류 방지 필요 |
| 권한 위임 | **OAuth 2.0**•**PKCE** | 제한 권한을 위임하되 범위•대상 제한 필요 |
| 서비스 신원 | **mTLS** | 통신 주체를 상호 인증하되 객체 권한은 별도 판정 |

#### 한줄 요약

- 계층형 통제는 전체 경로, JWT는 주장, OAuth는 위임, 상호 전송 계층 보안는 통신 주체를 보호한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **IETF RFC 9700(IETF RFC 9700)**: OAuth 2.0 보안 구현 시 준수해야 할 최신 보안 모범 사례 및 권고안을 명시한 인터넷 표준 문서.
- **OWASP API Top 10:2023(OWASP API Top 10:2023)**: API 환경에서 가장 치명적인 10가지 보안 위험 범주 및 방어 대책을 정리한 지침서.
- **객체 수준 인가 결함(Broken Object Level Authorization, BOLA)**: 다른 사용자의 객체 식별자를 조작하여 권한 없이 대상 리소스에 접근 가능한 보안 취약점.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| OAuth 흐름 오구성으로 토큰 탈취•재전송 | **IETF RFC 9700** 적용 | 토큰 탈취와 재전송 위험 완화 |
| 객체 인가 누락•무제한 호출로 정보 유출•과부하 | **OWASP API Top 10:2023** 점검 | **BOLA**•자원 소비 남용 방지 |
| 게이트웨이를 거치지 않은 직접 호출은 세부 권한 미검증 | 자원 서버의 **객체 인가**•**기능 인가**와 감사 수행 | 직접 호출의 권한 오용 차단 |

#### 한줄 요약

- 인증된 사용자가 거래 식별자를 바꿔 요청해도 서버가 해당 거래의 소유자를 다시 확인해 다른 고객의 정보를 반환하지 않는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **API 통제 선택 기준(API Control Selection Standard)**: 위임 방식, 서비스 신원, 객체 권한 및 자원 소비 통제 수단을 체계적으로 선택하는 지침.

</details>

- **API 통제 선택 기준**에 따라 외부 위임은 **OAuth 2.0**•**PKCE**, 서비스 신원은 **mTLS**, 모든 요청은 **객체 인가**•**호출률 제한** 적용.

#### 한줄 요약

- 보안 API는 토큰 검증과 객체 권한, 자원 제한, 키 수명 관리를 함께 운영해야 한다.
