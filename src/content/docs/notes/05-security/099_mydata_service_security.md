## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **마이데이터 서비스 보안**: 정보주체가 동의한 본인정보의 전송•수신•활용•철회 전 과정에서 주체•범위•목적을 결속해 보호하는 체계이다.
- **API(Application Programming Interface)**: 서비스 기능과 데이터를 정해진 요청•응답 형식으로 제공하는 경계이다.
- **베어러 토큰 위험**: 토큰을 가진 누구나 사용할 수 있으면 탈취자가 정상 클라이언트처럼 재전송하여 개인정보를 받을 수 있는 위험이다.

</details>

- 정의/개념: **API** 기반 동의•전송•수신•활용 전 과정을 보호하는 **마이데이터 서비스 보안** 체계이다.
- 배경/필요성: **베어러 토큰 위험** 때문에 토큰이 탈취되면 공격자가 정상 클라이언트처럼 재전송할 수 있다.

#### 한줄 요약

- 정보주체가 허락한 정보만 정한 기관에 정한 기간 동안 보내고 철회 시 이후 전송과 이용 근거를 함께 종료한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **동의 관리**: 전송 목적•항목•수신자•기간의 생성•변경•철회를 관리하는 활동이다.
- **최소 권한 토큰**: 동의한 범위•대상•만료를 반영한 접근 토큰이다.
- **기관 인증**: 전송자와 수신자의 신원을 상호 확인하는 절차이다.
- **요청 서명**: API 요청 내용의 위조•변조를 검증하는 통제이다.

</details>

- **동의 관리**로 목적•항목•수신자•기간을 결속한다.
- 대상•범위•만료를 제한한 **최소 권한 토큰**을 발급한다.
- **기관 인증**과 **요청 서명**으로 API 요청의 주체와 무결성을 확인한다.

#### 한줄 요약

- 동의 정보와 접근 토큰과 실제 응답 필드가 항상 일치해야 하며 동의가 바뀌면 보유 데이터의 이용 근거도 다시 판단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정보전송자**: 법정 대상 개인정보를 보유하고 요청에 따라 제공하는 기관이다.
- **정보수신자**: 전송받은 개인정보를 정보주체가 지정한 목적 안에서 활용하는 기관이다.
- **동의-토큰-필드 결속**: 정보주체가 허용한 항목과 인가 토큰의 범위, 실제 API 응답 필드를 끝까지 일치시키는 통제이다.

</details>

```text
마이데이터 서비스 보안 구조
├─ 동의•인가 경계
│  ├─ 정보주체•동의
│  └─ 인가 서버
├─ 전송 경계
│  ├─ 정보수신자
│  └─ 보호 API 채널
└─ 제공•감사 경계
   └─ 정보전송자•이력
```

선의 의미: 정보주체의 동의는 인가 서버의 토큰과 정보수신자 권한에 결속되고, 정보수신자는 기관 인증•전송 무결성을 제공하는 보호 API 채널을 통해 정보전송자•이력 경계에 연결되는 정적 마이데이터 보안 구조를 뜻한다.

| 구성요소 | 책임 |
|:---|:---|
| 정보주체•동의 | **동의 관리**로 목적•항목•수신자•기간 관리 |
| 인가 서버 | **최소 권한 토큰** 발급 |
| 정보수신자 | **정보수신자**가 동의 목적 안에서 데이터 활용 |
| 보호 API 채널 | **기관 인증**•**요청 서명** 적용 |
| 정보전송자•이력 | **정보전송자**가 토큰 검증•필드 전송•감사 수행 |

#### 한줄 요약

- **동의-토큰-필드 결속**으로 동의 관리기가 정한 범위를 인가 서버의 토큰과 정보전송자의 실제 응답 필드에 끝까지 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **송신자 제한 토큰**: 접근 토큰을 특정 클라이언트 키에 결속해 탈취자의 사용을 막는 자격이다.
- **Nonce**: 요청의 신규성을 확인해 재전송을 막는 일회성 난수이다.
- **파생 데이터 철회 처리**: 동의 철회 때 새 전송을 중단하고 원본을 가공해 만든 결과의 보유•이용 근거도 다시 판단해 기록하는 절차이다.
- **제한•송신자 결속 토큰 발급**: 주체•대상•범위•만료와 클라이언트 키를 접근 토큰에 묶는 단계이다.
- **서명•난수 포함 요청 생성**: 기관의 요청 서명과 일회성 난수를 API 호출에 포함하는 단계이다.
- **토큰•동의•요청 검증**: 토큰 주체•수신자•동의 범위와 요청 필드를 대조하는 단계이다.
- **철회•활용중단•파생본 기록**: 새 전송을 중단하고 원본•파생 데이터의 보유 근거와 삭제 결과를 기록하는 단계이다.

</details>

```text
목적•항목•수신자 동의
          |
          v
1. 제한•송신자 결속 토큰 발급
          |
          v
2. 서명•난수 포함 요청 생성
          |
      전송 요청
          |
          v
3. 토큰•동의•요청 검증
          |
    허용 필드 암호 전송
          |
   동의 철회 요청
          |
          v
4. 철회•활용중단•파생본 기록
```

### 동작 원리

1. **제한•송신자 결속 토큰 발급**: **송신자 제한 토큰**에 주체•대상•범위•만료를 결속한다.
2. **서명•난수 포함 요청 생성**: 기관 인증과 **Nonce**로 재전송을 방지한다.
3. **토큰•동의•요청 검증**: 정보주체•수신자•필드를 대조한다.
4. **철회•활용중단•파생본 기록**: **파생 데이터 철회 처리**로 보유 근거•삭제•증적을 관리한다.


#### 한줄 요약

- 철회하면 새 전송을 막고 기존 원본과 파생 데이터의 보유•이용 근거를 다시 판단하여 결과를 기록한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **마이데이터 보호 단계**: 동의•인가, 기관 간 API 전송, 수신 후 저장•철회에 서로 다른 통제를 적용하는 구분이다.
- **파생본 근거 재판정**: 동의 철회 뒤 가공 결과의 보유•이용 근거를 다시 확인하는 통제이다.

</details>

| 보호 단계 | 핵심 통제 | 대표 위험 |
|:---|:---|:---|
| 동의•인가 | **동의 관리**와 **최소 권한 토큰** | 계정 탈취•과다 동의 |
| API 전송 | **기관 인증**•**요청 서명**•**Nonce** | 토큰 탈취•요청 재전송 |
| 저장•철회 | **파생본 근거 재판정** | 목적 외 이용•잔존본 |

#### 한줄 요약

- **마이데이터 보호 단계**마다 위험과 통제는 다르지만 하나의 정보주체 동의 범위가 세 단계를 지배해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **보호법 제35조의2**: 법정 전송 대상과 수신자 요건을 규정한 조항이다.
- **OAuth(Open Authorization)**: 보호 자원의 제한된 접근 권한을 제3자 응용에 위임하는 인가 프레임워크이다.
- **IETF(Internet Engineering Task Force)**: 인터넷 기술 표준을 개발•공개하는 국제 공동체이다.
- **RFC(Request for Comments) 9700**: OAuth의 토큰 탈취•재사용•과권한 방어 지침을 제시하는 문서이다.
- **BCP(Best Current Practice) 240**: RFC 9700을 인터넷 모범 사례로 지정한 문서이다.
- **FAPI(Financial-grade API) 2.0**: 고보안 기관 API의 인가•송신자 결속•요청 무결성 요구를 규정한 프로파일이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 법정 전송 범위 | **보호법 제35조의2** 필드 대조 | 미동의•타인 정보 차단 |
| **OAuth** 토큰 공격 | **IETF**의 **RFC 9700**•**BCP 240** 적용 | 탈취•재사용•과권한 방지 |
| 고보안 기관 API | **FAPI 2.0** 프로파일 | 인증•인가 상호운용 강화 |

#### 한줄 요약

- 마이데이터 사업자는 토큰의 정보주체•수신자•동의 범위와 응답 필드를 대조하고 송신자 결속으로 탈취 토큰 재사용을 막는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **동의 지배 원칙**: 정보주체의 유효한 동의가 토큰 발급•전송 필드•원본과 파생 데이터 이용•철회 후 종료까지 일관되게 적용되어야 한다는 원칙이다.

</details>

- **동의 지배 원칙**에 따라 동의•토큰 주체•보유 근거가 일치할 때만 전송•이용하고 철회 시 중단한다.

#### 한줄 요약

- 마이데이터 보안의 핵심은 동의가 토큰 발급부터 전송 필드와 원본•파생 데이터의 보유 종료까지 지배하게 하는 것이다.
