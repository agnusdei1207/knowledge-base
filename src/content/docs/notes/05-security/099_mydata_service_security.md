## 미리 알고가기

- **마이데이터(MyData)**: 정보주체의 요구에 따라 본인 정보를 다른 기관이나 서비스로 전송하여 통합 조회·활용하는 서비스이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 기관 간 데이터 요청과 응답을 정해진 형식으로 교환하는 연결 규격이다.
- **접근 토큰**: 허용 범위와 기간을 담은 인가 정보
- **일회성 난수**: 요청 재사용을 판별하는 임시 값
- **정보 전송자**: 보유 데이터를 제공하는 기관
- **정보 수신자**: 전송받은 데이터를 활용하는 기관
- **파생 데이터**: 원본을 가공해 만든 결과 데이터

## Ⅰ. 개요

- 정의: 정보주체의 **전송 요구·동의 기반 보안**
- 기존 한계: 기관 중심 활용의 **통제권·투명성 부족**

### 쉽게 이해하기 (학습용)

- 허락한 정보만 정한 기관에 정한 기간 동안 보낸다.

## Ⅱ. 특징

- 목적·항목·기관·기간의 **동의 범위 결합**
- 범위·대상·만료 기반 **최소 권한 토큰**
- 기관 인증·요청 서명 기반 **API 무결성**

### 쉽게 이해하기 (학습용)

- 동의가 바뀌면 모든 보유본의 권한도 바뀌어야 한다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
  U["정보 주체"] --> C["동의 관리기"]
  C --> A["인가 서버"]
  A --> R["정보 수신자"]
  R --> P["보호 API 채널"]
  P --> S["정보 전송자"]
  L["전송·철회 이력"] --- C
  L --- R
  L --- S
```

| 구성요소 | 역할 |
|:---|:---|
| 정보 주체 | 전송 목적·항목·기관에 동의 |
| 동의 관리기 | 동의 생성·변경·철회 관리 |
| 인가 서버 | 범위·대상·만료 토큰 발급 |
| 정보 수신자 | 동의 목적에 따라 데이터 활용 |
| 보호 API 채널 | 기관 인증과 전송 무결성 제공 |
| 정보 전송자 | 토큰 검증 후 허용 항목 제공 |
| 전송·철회 이력 | 처리 증적과 이상 행위 기록 |

### 쉽게 이해하기 (학습용)

- 동의 정보가 토큰과 실제 전송 범위를 결정한다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
  participant U as 정보 주체
  participant C as 동의 관리기
  participant A as 인가 서버
  participant R as 정보 수신자
  participant S as 정보 전송자
  U->>C: 전송 범위 동의
  C->>A: 인가 조건 전달
  A-->>R: 제한 토큰 발급
  R->>S: 데이터 전송 요청
  S->>S: 토큰·요청 검증
  S-->>R: 허용 데이터 전송
  U->>C: 동의 철회
  C-->>R: 철회 상태 전달
  R->>R: 활용 중단·보유 정책 적용
```

| 절차 | 핵심 내용 |
|:---|:---|
| 전송 범위 동의 | 목적·기관·항목·기간 확정 |
| 인가 조건 전달 | 동의 내용을 인가 정책에 반영 |
| 제한 토큰 발급 | 대상·범위·만료를 토큰에 결합 |
| 데이터 전송 요청 | 토큰과 일회성 난수로 요청 |
| 토큰·요청 검증 | 서명·범위·재사용 여부 확인 |
| 허용 데이터 전송 | 동의한 필드만 암호화 전송 |
| 동의 철회 | 이후 전송·활용 권한 종료 |
| 철회 상태 전달 | 수신자에 동의 변경 통지 |
| 활용 중단·보유 정책 적용 | 원본·파생본의 처리 근거 재판단 |

> 동의 범위를 전송과 보유 데이터에 연결한다.

### 쉽게 이해하기 (학습용)

- 철회하면 새 전송과 기존 데이터 사용이 모두 멈춘다.

## Ⅴ. 종류 및 비교

| 마이데이터 보호 단계 | 동의·인가 보호 | API 전송 보호 | 저장·철회 보호 |
|:---|:---|:---|:---|
| 적용 기준 | 권한 생성·변경 시점 | 기관 간 데이터 이동 | 수신 후 활용·종료 |
| 핵심 특징 | 범위 제한 토큰 발급 | 기관 인증·요청 검증 | 목적별 격리·철회 반영 |
| 한계 | 계정 탈취·과다 동의 | 토큰 탈취·재전송 | 목적 외 이용·잔존본 |

> 단계별 통제를 하나의 동의 범위로 묶는다.

### 쉽게 이해하기 (학습용)

- 허락·이동·보관 단계마다 다른 위험을 막는다.

## Ⅵ. 실무 사례

1. 금융정보 전송의 **토큰 주체·동의 필드 대조**

### 쉽게 이해하기 (학습용)

- 마이데이터 사업자는 접근 토큰의 정보주체·수신자·동의 범위와 응답 필드를 대조해 다른 사람의 정보나 미동의 항목이 전달되지 않게 한다.

## Ⅶ. 결론

- 개인 금융정보의 과잉 전송과 재사용을 막기 위해 토큰 주체·동의 범위·보유 근거·철회·파생 데이터를 검토하여, 마이데이터 전 수명주기에 목적 제한을 적용해야 한다.

### 쉽게 이해하기 (학습용)

- 동의가 데이터의 전체 생애주기를 지배해야 한다.
