## 미리 알고가기

- **랜섬웨어(Ransomware)**: 데이터 암호화·유출·서비스 방해를 이용해 금전을 요구하는 악성코드와 침해 활동
- **암호화 갈취(Encryption Extortion)**: 파일을 사용할 수 없게 암호화하고 복구 대가를 요구하는 방식
- **이중 갈취(Double Extortion)**: 데이터 암호화와 유출 공개 협박을 함께 사용하는 방식
- **다중 갈취(Multiple Extortion)**: 암호화·유출에 서비스 거부·고객 압박 등을 더하는 방식
- **초기 접근(Initial Access)**: 공격자가 피싱·취약점·탈취 계정으로 내부에 처음 진입하는 단계
- **권한 상승(Privilege Escalation)**: 일반 권한에서 관리자 등 더 높은 권한을 얻는 공격 행위
- **측면 이동(Lateral Movement)**: 침해한 장비에서 다른 내부 자원으로 공격 범위를 넓히는 행위
- **명령·제어(Command and Control, C2)**: 공격자가 침해 장비에 원격 명령을 전달하고 실행 결과를 수신하는 통신
- **불변 백업(Immutable Backup)**: 정해진 보존 기간 동안 수정·삭제할 수 없도록 보호한 백업
- **오프라인 백업(Offline Backup)**: 평상시 운영망과 연결되지 않아 원격 공격이 직접 접근하기 어려운 백업
- **복구 신뢰 경계(Recovery Trust Boundary)**: 운영 계정·관리면과 분리해 백업과 복구 권한을 보호하는 영역
- **섀도 복사본(Shadow Copy)**: 운영체제가 특정 시점의 파일·볼륨 상태를 저장한 복사본
- **분산 서비스 거부(Distributed Denial of Service, DDoS)**: 다수의 공격원이 서비스 자원을 고갈시켜 정상 이용을 방해하는 공격
- **침해지표(Indicator of Compromise, IOC)**: 악성 파일·주소·계정 행위 등 시스템 침해를 식별하는 관측 흔적

## Ⅰ. 개요

- 정의/개념: 암호화·유출·서비스 방해로 **금전 지불을 압박하는 침해**
- **배경/필요성**: 파일 백업만으로는 **탈취 신원·유출 데이터 복구 불가**

### 쉽게 이해하기 (학습용)

- 랜섬웨어는 파일을 잠그는 순간 시작되는 공격이 아니라 그전에 관리자 계정과 백업을 장악하고 데이터를 빼낸 뒤 마지막에 잠금 화면을 보여 주는 침해다.

## Ⅱ. 특징

- **초기 접근·권한 상승·측면 이동**으로 관리·백업 권한을 장악한다.
- **유출 후 암호화**로 복구와 공개 협박을 동시에 압박한다.
- **보안 도구·로그·백업 선제 무력화**로 탐지·복구를 방해한다.

### 쉽게 이해하기 (학습용)

- 백업으로 파일을 되살려도 공격자가 가져간 문서와 계정 비밀은 되돌아오지 않으므로 유출과 신원 침해를 별도로 처리해야 한다.

## Ⅲ. 구성요소 및 구조

```mermaid
flowchart LR
    A[초기 접근·C2] --> B[권한·신원 장악]
    B --> C[측면 이동·유출]
    C --> D[복구 방해·암호화]
    D --> E[갈취·사고 대응]
    F[복구 신뢰 경계] --> D
    F --> E
```

| 설계 요소 | 설명 |
|:---|:---|
| 초기 접근·C2 | **침투 경로·원격 명령 유지** |
| 권한·신원 장악 | **관리자·서비스 계정 탈취** |
| 측면 이동·유출 | **중요 자산 탐색·데이터 반출** |
| 복구 방해·암호화 | **보안·백업 훼손 후 자산 잠금** |
| 갈취·사고 대응 | **협박·통지·수사·복구 조정** |
| 복구 신뢰 경계 | **분리 계정·불변 백업 보호** |

> 요약: 공격 경로와 복구 경계를 분리해 대응

### 쉽게 이해하기 (학습용)

- 공격자는 진입점에서 관리자와 백업까지 이동하고 방어자는 운영 환경과 분리된 복구 경계로 그 확산을 끊고 시스템을 되살린다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant D as 탐지 체계
    participant I as 사고 대응팀
    participant N as 신원·네트워크 통제
    participant R as 복구 환경
    participant L as 법무·통지 체계
    D->>I: 랜섬웨어 사건 통보
    I->>N: 확산 경로 격리 요청
    N-->>I: 차단·자격 교체 결과
    I->>R: 신뢰 복구 요청
    R-->>I: 검증 복원 결과
    I->>L: 유출·영향 범위 전달
```

| 절차 | 설명 |
|:---|:---|
| 랜섬웨어 사건 통보 | 암호화·유출·C2 흔적 확인 |
| 확산 경로 격리 요청 | 호스트·구간·관리면 분리 |
| 차단·자격 교체 결과 | C2 차단과 관리자 비밀 폐기 |
| 신뢰 복구 요청 | 깨끗한 관리면과 백업 선택 |
| 검증 복원 결과 | 악성 잔존과 업무 기능 확인 |
| 유출·영향 범위 전달 | 통지·수사·고객 대응 수행 |

> 요약: 공격 통로를 닫은 뒤 깨끗한 경계에서 복구한다.

### 쉽게 이해하기 (학습용)

- 감염 장비만 복원하면 공격 계정이 다시 암호화할 수 있으므로 먼저 통신과 자격을 끊고 깨끗한 관리면에서 검증된 백업을 복원한다.

## Ⅴ. 종류 및 비교

| 랜섬웨어 갈취 방식 | 랜섬웨어 공통 | 암호화 갈취 | 이중 갈취 | 다중 갈취 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 랜섬웨어 사고 통합 대응 | 복원 가능성 중심 분석 | 유출·통지 동시 대응 | 법무·평판·가용성 통합 |
| 핵심 특징 | 업무 중단·금전 요구 | 데이터 잠금 중심 | 잠금·유출 협박 | 방해·고객 압박 결합 |
| 한계 | 신원·백업 동시 침해 | 복호화 실패·재감염 | 유출 데이터 회수 불가 | 제3자 피해·압박 확대 |

> 요약: 암호화·유출·방해가 갈취 범위를 확장

### 쉽게 이해하기 (학습용)

- 암호화형은 복구를 막고 이중형은 공개 협박을 더하며 다중형은 서비스 방해와 고객 압박까지 더해 지불 압력을 키운다.

## Ⅵ. 실무 사례

1. 복구 환경은 **운영 관리자와 백업 계정 분리**

### 쉽게 이해하기 (학습용)

- 운영 관리자 계정이 탈취돼도 같은 권한으로 백업을 삭제하지 못하게 복구 계정을 분리한다.

## Ⅶ. 결론

- 랜섬웨어의 암호화와 정보 유출 피해를 줄이기 위해 감염 범위·확산 경로·백업 신뢰·유출 증거·자격 탈취를 검토하여, 격리·신뢰 복구·통지·자격 교체를 수행해야 한다.

### 쉽게 이해하기 (학습용)

- 랜섬웨어 대응은 잠긴 파일을 푸는 작업이 아니라 공격자가 차지한 신뢰를 걷어 내고 깨끗한 환경에서 업무와 데이터 책임을 함께 복구하는 과정이다.
