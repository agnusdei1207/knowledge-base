## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **IDS (Intrusion Detection System)**: 미러링(SPAN/TAP) 트래픽을 수동 분석하여 공격 탐지 시 경보를 발행하는 사후 모니터링 시스템.
- **IPS (Intrusion Prevention System)**: 네트워크 경로에 직렬(Inline) 배치되어 악성 패킷을 실시간 폐기(Drop)하는 능동 방어 시스템.

</details>

- 정의/개념: IDS 탐지와 IPS 차단으로 구성된 **침입 대응 시스템**
- 배경/필요성: 방화벽은 세션 수립 여부만 판정해 허용된 포트로 들어온 페이로드는 그대로 통과시키므로, 방화벽 뒤에 페이로드를 재조합해 공격 패턴과 대조하는 검사 계층을 두고 경보만 낼지(IDS) 경로에 직렬로 끼어들어 폐기할지(IPS)를 가용성 비용으로 나눌 필요

#### 한줄 요약
- 미러링 기반 수동 감시(IDS)와 인라인 기반 실시간 차단(IPS)을 통해 네트워크 침입을 무력화한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Signature vs Anomaly Detection**: 알려진 공격 패턴과 대조하는 시그니처 기반 탐지와 정상 트래픽 기준선을 벗어나는 변종을 탐지하는 이상행위 탐지.
- **Hardware Bypass (Fail-Open)**: IPS 장비의 전원 이상이나 장애 시 물리 릴레이 스위치를 직결하여 회선 단절을 방지하는 안전장치.

</details>

- **배치 방식 분리**: 미러링 **IDS**, 인라인 **IPS** 분업
- **복합 탐지**: 시그니처와 **이상행위 기준선** 결합
- **패킷 정규화**: 단편·스트림을 복원해 **우회 공격 탐지**

#### 한줄 요약
- 시그니처는 오탐이 적은 대신 알려진 공격만 잡고 이상행위는 변종을 잡는 대신 오탐을 늘리므로, 두 방식의 병용은 곧 미탐과 오탐 중 어느 쪽 비용을 더 감당할지를 구간별로 정하는 일이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Stream Reassembler (패킷 정규화기)**: 조각난 IP 패킷과 비순차 TCP 세그먼트를 원본 스트림으로 재조합하여 시그니처를 검사하는 모듈.

</details>

```text
[IDS·IPS 구성]
|-- 트래픽 센서      : 인라인·미러링 수집
|-- 패킷 정규화기    : 단편·스트림 복원
|-- 탐지 엔진        : 시그니처·이상 분석
|-- 대응 제어기      : 경보·차단 집행
`-- 바이패스 모듈    : 장애 시 회선 유지
```

선의 의미: IPS는 실제 네트워크 경로 중간에 직렬로 연결되어 악성 패킷을 직접 폐기하고 IDS는 스위치 미러링 포트를 통해 복사본을 수동 분석하는 구조

| 구성요소 | 책임 |
|:---|:---|
| 트래픽 센서 | **인라인·TAP/SPAN** 패킷 수집 |
| 패킷 정규화기 | 단편 재조합과 **스트림 복원** |
| 탐지 엔진 | **시그니처·이상행위** 분석 |
| 대응 제어기 | **경보·Drop·TCP RST** 집행 |
| 바이패스 모듈 | 장애 시 **Fail-Open** 회선 유지 |

#### 한줄 요약
- 정규화기는 탐지 엔진 앞에 놓여 공격자가 단편화로 흐트러뜨린 페이로드를 원본 스트림으로 되돌려 놓고, 바이패스 모듈은 인라인 배치가 새로 만들어 낸 단일 장애점을 회선 직결로 되돌리는 보상 장치다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TCP Reset Injection**: IDS가 미러링 망에서 공격 탐지 시 공격자와 피해자 양단에 위조된 TCP RST 패킷을 주입하여 세션을 강제 종료시키는 기법.

</details>

```text
원시 패킷
    |
 1. 패킷 캡처
    |
 2. 스트림 정규화
    |
 3. 위협 탐지
    +-- 정상: 목적지 전달
    `-- 악성
         +-- IDS: 경보·기록
         `-- IPS: 패킷 차단
```

동작 원리

1. 패킷 캡처
2. 스트림 정규화
3. 위협 탐지

#### 한줄 요약
- 악성 판정 이후 갈리는 두 갈래는 오판의 대가가 정반대여서, IDS의 경보는 틀려도 통신을 해치지 않는 대신 침해가 진행되고 IPS의 폐기는 맞으면 즉시 막지만 틀리면 정상 서비스를 끊는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **IDS (침입 탐지)**: 스위치 미러링 포트로 복사본만 받아 경로 밖(Out-of-Band)에서 분석하므로 검사 지연도 장애 전파도 통신에 얹지 않는 대신, 판정 시점에는 이미 원본 패킷이 목적지에 도착해 있는 배치 방식.
- **IPS (침입 방지)**: 트래픽 경로 위에 직렬로 끼어들어 판정 전까지 패킷을 붙잡아 두고 악성이면 폐기하므로 침해 자체를 막는 대신, 검사 지연과 장비 장애가 그대로 회선 품질에 반영되는 배치 방식.

</details>

| 비교 항목 | 침입 탐지 시스템 (IDS: Detection) | 침입 방지 시스템 (IPS: Prevention) |
|:---|:---|:---|
| 물리적 배치 방식 | **Out-of-Band** | **In-Line** |
| 주요 동작 방식 | 복사본 분석과 **경보** | 실제 패킷 **차단** |
| 네트워크 지연 | 없음 | 검사 지연 발생 |
| 장비 장애 시 영향 | 통신 영향 없음 | **SPOF 위험** |
| 오탐 영향 | Alert Fatigue | 정상 서비스 차단 |
| 권장 구축 영역 | 고가용 코어·관제망 | 인터넷 경계·DMZ |

#### 한줄 요약
- IDS는 가용성이 중요한 백본망 수동 감시용, IPS는 경계망 실시간 능동 방어용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Phased Deployment (단계적 차단 배포)**: 신규 IPS 룰셋 적용 시 2~4주간 모니터링(Detection-Only) 모드로 선운영하여 오탐을 정제한 후 차단으로 전환하는 운영 프랙티스.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신규 규칙 오탐으로 **정상 트래픽 차단** | **Alert-Only 선운영** 후 단계 전환 | 오탐과 서비스 중단 방지 |
| 단편·인코딩으로 **탐지 우회** | **스트림 재조합·정규화** | 검사 사각지대 제거 |
| IPS 장애로 **통신 단절** | **하드웨어 Fail-Open** | 네트워크 가용성 확보 |
| HTTPS 내부 **공격 미탐지** | **TLS 복호화 프록시** 연동 | 암호화 위협 가시성 확보 |

#### 한줄 요약
- 단계적 배포로 오탐을 방지하고, 스트림 정규화로 Evasion을 막으며, 하드웨어 바이패스로 SPOF를 방지한다.

## Ⅶ. 결론

- 가용성 우선 구간은 **IDS**, 실시간 차단 구간은 **IPS** 선택

#### 한줄 요약
- IDS와 IPS는 가용성 모니터링과 실시간 인라인 차단 및 바이패스 안전망을 결합하여 고신뢰 네트워크 침입 방어를 실현하는 핵심 시스템이다.
