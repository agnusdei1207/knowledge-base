## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **침입 탐지 시스템(Intrusion Detection System, IDS)**: 네트워크 선로에서 미러링(SPAN/TAP)된 트래픽 복사본을 수동적으로 수신하여, 알려진 공격 시그니처나 비정상 행위를 분석하고 관리자에게 경보(Alert) 및 로그를 생성하는 사후 모니터링 보안 시스템.
- **침입 방지 시스템(Intrusion Prevention System, IPS)**: 실제 네트워크 트래픽 경로상에 직렬(Inline)로 배치되어, 인입되는 패킷을 실시간 심층 검사(DPI)하여 악성 페이로드 발견 즉시 해당 패킷을 능동적으로 폐기(Drop)하거나 TCP 세션을 강제 종료(TCP RST)시키는 실시간 방어 시스템.

</details>

- 정의/개념: 트래픽 처리 방식에 따라 비인가 공격을 수동 감시하는 **미러링 기반 IDS** 와 능동 차단하는 **인라인 기반 IPS** 로 구분되며, 패킷 정규화(Normalization) 및 시그니처/이상행위 탐지 엔진을 탑재한 **네트워크 침입 제어 아키텍처**
- 배경/필요성: L3/L4 경계 방화벽이 정상 포트(80, 443)로 위장하여 유입되는 버퍼 오버플로우, 원격 코드 실행(RCE), SQL Injection 등 L7 애플리케이션 악성 페이로드를 필터링하지 못하는 구조적 취약점을 보완할 요구

#### 한줄 요약
- IDS는 미러링 기반 수동 탐지 및 경보를 수행하고, IPS는 인라인 기반 실시간 패킷 폐기 및 차단을 집행한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **시그니처 기반(Signature-Based / 오용 탐지)**: 기 구축된 공격 패턴 데이터베이스(CVE 취약점 시그니처)와 패킷 페이로드를 1:1 패턴 매칭하여 알려진 공격을 높은 정확도로 탐지하는 방식.
- **이상 행위 기반(Anomaly-Based / 비정상 탐지)**: 정상 네트워크 트래픽의 베이스라인(트래픽 양, 프로토콜 분포)을 통계/머신러닝으로 학습한 후, 임계치를 벗어나는 급격한 편차를 감지하여 미지의 제로데이(Zero-Day) 공격을 식별하는 방식.

</details>

- **가용성 무영향 vs 실시간 차단 (SPAN vs Inline)**: IDS는 장비 장애 시에도 라이브 서비스 무영향, IPS는 즉각적인 차단력을 제공하나 단일 장애점(SPOF) 리스크 수반
- **오탐(False Positive)과 미탐(False Negative)의 상충 관계**: 차단 정책이 과도하면 정상 비즈니스 트랜잭션이 유실(오탐)되고, 완화하면 악성 침입을 허용(미탐)
- **우회 공격 방어 (Packet Normalization)**: 공격자가 패킷 단편화(IP Fragmentation)나 URL 이중 인코딩으로 시그니처 매칭을 회피(Evasion)하는 것을 방지하기 위해 스트림 재조합 필수

#### 한줄 요약
- 미러링(가용성) vs 인라인(차단력), 시그니처 vs 이상행위 탐지, 패킷 정규화 기반 회피 공격 방어를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **패킷 정규화기(Packet Normalizer / Stream Reassembler)**: 단편화(Fragmented)되어 조각난 IP 패킷과 비순차 TCP 세그먼트를 메모리 버퍼에서 원본 스트림으로 온전히 재조합하고 디코딩하여 시그니처 검사 엔진에 전달하는 전처리 모듈.

</details>

```text
[ 1. 인라인 IPS 배치 구조 (직렬 연결) ]
[ 외부 인터넷 ] ──▶ [ 하드웨어 바이패스 스위치 ] ──▶ [ 인라인 IPS 엔진 (DPI & Drop) ] ──▶ [ 내부 서버망 ]

[ 2. 미러링 IDS 배치 구조 (병렬 연결) ]
[ 외부 인터넷 ] ──────────────────▶ [ 백본 스위치 (SPAN/TAP) ] ──────────────────▶ [ 내부 서버망 ]
                                              │ (트래픽 복사본 전송)
                                              ▼
                                 [ 수동 모니터링 IDS 엔진 (Alert & SIEM 전송) ]
```

선의 의미: IPS는 실제 네트워크 경로 중간에 직렬로 연결되어 악성 패킷을 직접 폐기하고, IDS는 스위치 미러링 포트를 통해 복사본을 수동 분석하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **트래픽 수집 센서** | 인라인 물리 인터페이스(IPS) 또는 광 TAP/SPAN 포트(IDS)로부터 원시 패킷 캡처 | Sensor Interface |
| **패킷 정규화기 (Decoder)** | IP 단편화 재조합, TCP 스트림 리어셈블리, URL/Base64 난독화 디코딩 수행 | Normalizer |
| **탐지 분석 엔진** | Snort/Suricata 룰 기반 시그니처 매칭 및 휴리스틱/통계 이상 행위 분석 | Inspection Engine |
| **능동 대응 제어기** | 위협 탐지 시 패킷 드롭(Drop), TCP RST 플래그 주입, 또는 SNMP Trap/Syslog 발행 | Action Controller |
| **하드웨어 바이패스 모듈** | IPS 장비의 전원 이상, OS 크래시 발생 시 물리 릴레이 스위치를 직결하여 회선 유지 | Fail-Open Bypass |

#### 한줄 요약
- 트래픽 수집 센서, 패킷 정규화기, 탐지 분석 엔진, 능동 대응기, 하드웨어 바이패스가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **TCP RST 인젝션(TCP Reset Injection)**: IDS가 미러링 망에서 공격을 탐지했을 때, 직접 패킷을 차단할 수 없으므로 공격자와 피해자 양단에 위조된 TCP RST(Reset) 패킷을 능동 주입하여 해당 TCP 연결을 강제 파기시키는 대책 기술.

</details>

```text
1. 네트워크 인터페이스로 인입되는 원시 패킷 캡처 (IPS: 직렬 수신 / IDS: 미러링 복사본 수신)
            │
            ▼
2. [패킷 정규화] IP 단편화 조각 재조합, TCP 시퀀스 정렬 및 다중 URL 인코딩 해제
            │
            ▼
3. [위협 분석] Snort 시그니처 데이터베이스 대조 및 통계적 프로파일링 이상 행위 판정
            │
            ├─ [정상 패킷으로 판정] ➔ 목적지 포트로 무지연 포워딩
            ▼
4. [악성 위협 탐지 시 정책 집행]
    ├─ [IDS 모드]: 침입 로그 생성 ➔ SIEM/SOC 관제 전송 및 필요 시 TCP RST 주입
    └─ [IPS 모드]: 해당 악성 패킷 즉각 폐기(Drop) ➔ 공격지 IP 임시 블랙리스트 차단 등록
```

**동작 원리**

1. **원시 패킷 인입**: 고속 캡처 드라이버(DPDK/AF_PACKET)를 통해 제로 카피로 버퍼 로드
2. **스트림 정규화**: 분할 전송된 시그니처 파편을 단일 문자열로 복원하여 우회 기법 무력화
3. **규칙 엔진 평가**: Aho-Corasick 다중 패턴 매칭 알고리즘으로 수만 개의 CVE 룰셋 병렬 스캔
4. **동적 차단 조치**: IPS는 NIC 드롭 또는 커널 레벨 패킷 폐기 집행, IDS는 감사 이벤트 로깅
5. **사후 피드백**: 관제 센터(SOC) 분석가가 오탐 여부를 검토하여 룰셋 튜닝 반영

#### 한줄 요약
- 패킷 캡처, 정규화 스트림 복원, 시그니처/이상 탐지, IDS 로깅 또는 IPS 실시간 드롭 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **IDS vs IPS 심층 비교**: 배치 방식, 처리 지연시간, 가용성 영향, 오탐/미탐 리스크 분석.

</details>

| 비교 항목 | 침입 탐지 시스템 (IDS: Detection) | 침입 방지 시스템 (IPS: Prevention) |
|:---|:---|:---|
| **물리적 배치 방식** | **수동적 병렬 배치 (Out-of-Band / TAP, SPAN)** | **능동적 직렬 배치 (In-Line)** |
| **주요 동작 방식** | 패킷 복사본 분석 후 **로그 기록 및 경보(Alert) 발생** | 실제 패킷 검사 후 **악성 트래픽 실시간 폐기(Drop/Reject)** |
| **네트워크 지연 (Latency)**| **지연 없음 (0ms, 라이브 경로 외부 동작)** | **수 밀리초 검사 지연 발생 (1~5ms)** |
| **장비 장애 시 영향** | **가용성 무영향 (네트워크 정상 가동 유지)** | **통신 단절 위험 (단일 장애점 SPOF 발생 가능)** |
| **오탐(False Positive) 영향**| 보안 관제사의 경보 피로도(Alert Fatigue) 증가 | **정상 고객 서비스 트랜잭션 차단 및 서비스 마비 장애**|
| **주요 권장 구축 영역** | **고가용성이 절대적인 금융 거래 코어망, 모니터링망** | **외부 침입 위협에 노출된 인터넷 경계망, DMZ 전면** |

#### 한줄 요약
- IDS는 가용성이 중요한 백본망 수동 감시용, IPS는 경계망 실시간 능동 방어용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **단계적 차단 배포(Phased Deployment / Monitor-First)**: 신규 IPS 도입 또는 새로운 시그니처 룰셋 적용 시, 즉시 차단(Inline Drop)을 활성화하지 않고 2~4주간 모니터링(Detection-Only) 모드로 선운영하여 정상 트래픽과의 오탐 매칭을 정제한 후 차단 모드로 전환하는 운영 프랙티스.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신규 IPS 시그니처의 과도한 매칭으로 인한 **정상 비즈니스 트래픽 오탐(False Positive) 차단 장애** | **신규 룰셋 적용 시 2주간 모니터링(Alert-Only) 선운영 후 단계적 차단(Inline Drop) 전환** | 오탐으로 인한 서비스 다운타임 0% 달성 및 시그니처 정밀 튜닝 |
| 공격자가 패킷 단편화(Fragmentation) 및 URL 인코딩을 조작하여 **IPS 시그니처를 우회하는 Evasion 공격** | **세션 스트림 재조합 및 다중 인코딩(UTF-8/Hex) 복원 정규화(Normalization) 엔진 강화** | 단편화 우회 공격 100% 탐지 및 시그니처 검사 사각지대 소거 |
| 인라인 IPS 장비의 하드웨어 고장 또는 OS 크래시로 인한 **사내망 전체 통신 단절(SPOF 장애)** | **전원/시스템 장애 시 물리 광스위치를 강제 직결하는 하드웨어 바이패스(Fail-Open) 장착** | 인라인 보안 장비 고장 시에도 네트워크 회선 가용성 100% 보장 |

#### 한줄 요약
- 단계적 배포로 오탐을 방지하고, 스트림 정규화로 Evasion을 막으며, 하드웨어 바이패스로 SPOF를 방지한다.

## Ⅶ. 결론

- 네트워크 경계 및 내부망 침입 위협을 차단하는 **IDS 및 IPS 아키텍처**는 가용성(Availability)과 보안성(Security)의 균형을 유지하는 핵심 통제 수단이며, 실무 구현 시 **외부 경계망의 인라인 IPS 및 코어 백본망의 미러링 IDS 이원화**, **하드웨어 바이패스(Fail-Open) 안전망 확보**, **패킷 정규화 및 모니터링 기반 단계적 차단(Phased Deployment) 거버넌스**를 통합 구축하여 무결점 네트워크 침입 방어 환경을 완성

#### 한줄 요약
- IDS의 가용성 모니터링과 IPS의 실시간 인라인 차단 및 바이패스 안전망을 결합하여 고신뢰 침입 방어를 실현한다.
