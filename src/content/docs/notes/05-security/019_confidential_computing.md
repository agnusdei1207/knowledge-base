## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기밀 컴퓨팅 (Confidential Computing)**: 클라우드 서버 관리자나 딥웹 해커조차도 메모리 안에서 무슨 연산이 돌아가는지 팩트로 절대 못 보게, 하드웨어(CPU) 자체에 물리적 안심 금고를 치는 기술이다.
- **사용 중 데이터 (Data in Use)**: 하드디스크에 저장될 때나 네트워크로 날아갈 땐 암호화가 되지만, 막상 CPU나 RAM에서 계산할 땐 팩트로 알몸(평문) 상태가 되는 가장 취약한 데이터 구간이다.

</details>

- 정의: 하드웨어 기반의 신뢰 실행 환경(TEE)을 이용해 메모리 위에서 연산 중인 데이터의 팩트 기밀성을 보장하는 최신 클라우드 보안 기술이다.
- 배경: 저장이나 전송 중 암호화를 아무리 잘해도, 클라우드 메모리(RAM)에 올라가는 순간 평문이 되어 서버 관리자 권한(Root)에 팩트로 털리는 치명적 구멍이 존재했다.

#### 한줄 요약

- 남의 컴퓨터(클라우드)를 빌려 쓰면서도, 서버 주인조차 내 데이터 연산 과정을 훔쳐보지 못하게 하드웨어 철벽을 치는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **TEE (신뢰 실행 환경)**: 클라우드 CPU 안에 물리적으로 두꺼운 벽을 쳐서, 서버 최고 관리자(Root) OS조차도 문을 못 열고 들여다보지 못하게 만든 팩트 방공호다.
- **원격 증명 (Remote Attestation)**: "그 서버 방공호 진짜 인텔/AMD 정품 맞고, 해킹 안 당했지?" 하고 원격으로 깐깐하게 팩트 체크(신원 및 무결성 확인)하는 절차다.
- **부채널 공격 방어**: 방공호 안은 절대 못 보니까, "밖에서 들리는 팬 소음이나 전력 소모량(부채널)으로 안에서 뭐 하는지 때려 맞춰야지!" 하는 얍삽한 해킹을 팩트로 막아내는 추가 방벽이다.

</details>

- **팩트 하드웨어 격리**: 서버의 소프트웨어(OS, 하이퍼바이저)가 완전히 털려도, 하드웨어(CPU) 단에서 메모리를 강제 암호화해 팩트로 방어한다.
- **팩트 신분 검증 (원격 증명)**: TEE가 정품 칩셋이 맞고 내 코드가 변조되지 않았음을 수학적으로 입증해야만, 비로소 데이터 압축을 풀 수 있는 진짜 암호키를 팩트로 내어준다.
- **팩트 부채널 통제 병행**: 방공호 밖에서 일어나는 캐시 메모리 패턴이나 전력 파형 등 물리적 꼼수 해킹을 원천 차단하기 위한 통제가 팩트로 병행된다.

#### 한줄 요약

- 클라우드 OS가 털려도 CPU가 버텨주고(TEE), 정품 인증(원격 증명)이 끝나야만 열쇠를 주며, 밖에서 엿듣는 꼼수(부채널)까지 쳐낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **측정값 (Measurement)**: 방공호(TEE) 안에 들어간 내 프로그램이 해커한테 변조됐는지 안 됐는지 팩트 확인하려고, 코드 원본을 해시 함수로 지문을 떠놓은 거다.
- **키 브로커 (Key Broker)**: "원격 증명 통과했네? 정품 방공호에 변조도 안 됐구나. 자, 데이터 풀 수 있는 열쇠 줄게." 하고 팩트 확인 후 열쇠를 내어주는 깐깐한 클라우드 보관소다.

</details>

```text
[ 기밀 컴퓨팅 팩트 실행 및 인증 아키텍처 ]

[ 1. TEE 하드웨어 (방공호) ] ── (CPU 칩셋 자체가 지원하는 물리적인 암호화 격리 공간)
      │
      ▼
[ 2. 보호 워크로드 ] ── (이 방공호 안에서 안전하게 팩트로 돌아가는 내 AI 모델이나 프로그램)
      │
      ▼ (방공호 정품 인증서랑 코드 지문을 외부로 던지면)
[ 3. 증명 검증기 (원격 검증) ] ── ("오, 정품 TEE 맞고 코드 변조 안 됐네!" 하고 팩트 도장 쾅 찍어줌)
      │
      ▼
[ 4. 키 브로커 (열쇠 배달) ] ── (검증 통과했으니, 그 방공호에서만 열 수 있게 팩트 포장해서 암호키 던져줌)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **TEE 하드웨어 (격리)** | OS나 서버 관리자도 못 건드리게 **CPU 차원에서 메모리를 암호화하고 팩트로 벽을 침** | TEE |
| **보호 워크로드 (프로그램)** | TEE 방공호 안으로 들어가서 **안전하게 실행되는 가장 민감한 팩트 연산 코드** | Workload |
| **증명 검증기 (검사소)** | TEE가 뱉은 정품 인증서와 지문을 보고 **해킹 안 당했는지 팩트로 깐깐하게 심사함** | Verifier |
| **키 브로커 (열쇠고리)** | 검사를 통과한 정당한 TEE한테만 **암호키를 안전하게 래핑(포장)해서 팩트로 전달함** | Broker |

#### 한줄 요약

- CPU 방공호(TEE) 안에 코드를 밀어 넣고 $\to$ 밖에서 검사(원격 증명)한 다음 $\to$ 합격해야만 열쇠(브로커)를 던져준다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **키 래핑 (Key Wrapping)**: 키 브로커가 암호키를 배달할 때, 클라우드 관리자가 중간에서 가로채지 못하도록 오직 대상 TEE 방공호만 풀 수 있는 자물쇠로 팩트 포장(암호화)해서 던지는 거다.

</details>

```text
[ 기밀 컴퓨팅 증명 및 암호키 팩트 바인딩 흐름 ]

┌──────────────────────────────┐
│ 1. [TEE 로딩 및 측정값(지문) 팩트 생성]
│ (내 코드가 방공호에 들어가면서 코드 원본의 지문을 찍고 TEE 서명을 팩트로 덧붙임)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [원격 증명서 전송 및 팩트 심사 (검증기)]
│ (검증기가 지문과 서명을 보고 "가짜 방공호 아니네, 해킹도 안 당했네" 팩트 심사함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [키 해제 팩트 승인 (키 브로커)]
│ (심사 통과 소식을 들은 키 브로커가 "열쇠 내어줘도 좋다"고 팩트 승인함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [대상 TEE 전용으로 열쇠 래핑(포장) 및 팩트 배달]
│ (중간 관리자가 못 훔치게, 오직 그 방공호만 풀 수 있게 열쇠를 팩트로 래핑해서 줌)
└──────────────────────────────┘
```

### 동작 원리

1. 측정값(지문) 생성: TEE 로딩 시 하드웨어가 팩트 지문을 산출하고 제조사 루트 키로 서명 증거를 만듦.
2. 원격 증명 정책 검증: 검증기(Verifier)가 증거를 받아 정책에 부합하는지, 코드가 무결한지 팩트 심사함.
3. 키 해제 승인: 검증 통과 시 키 브로커(KBS)가 데이터 암호키 발급을 팩트 승인함.
4. 비밀 래핑 전달: 승인된 TEE의 전용 공개키로 암호키를 래핑(Wrapping)하여 안전하게 팩트로 꽂아줌.

#### 한줄 요약

- 지문 찍어서 내고 $\to$ 심사받고 $\to$ 통과하면 $\to$ 아무도 못 뜯게 포장된 팩트 열쇠를 받아서 연산 시작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **엔클레이브 (Enclave)**: 앱 전체 말고 딱! 제일 민감한 함수 하나만 핀셋으로 집어서 방공호에 넣는 팩트 방식이다. (Intel SGX)
- **기밀 가상머신 (CVM)**: "코드 뜯어고치기 귀찮아!" 하며 가상머신(VM) 전체의 OS와 메모리를 통째로 방공호에 넣는 팩트 방식이다. (AMD SEV)
- **가속기 TEE**: CPU 방공호는 좁으니까, 아예 비싼 외장 그래픽카드(GPU) 메모리 전체를 방공호로 만들어서 AI를 팩트로 쌩쌩 돌리는 최신 기술이다.

</details>

| 기밀 컴퓨팅 방식 | **애플리케이션 엔클레이브** | **기밀 가상머신 (CVM)** | **가속기 TEE (GPU/NPU)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **딱 필요한 놈만 '1인용 방공호' 넣음** | **귀찮으니 집(VM) 통째로 '돔(Dome)' 씌움** | **AI 전용으로 '대형 공장 방공호' 지음** |
| 핵심 기술 원리 | 프로그램 소스코드를 뜯어고쳐서, **가장 민감한 특정 함수(모듈)만 팩트로 격리함** | 기존 앱을 단 1줄도 수정 안 하고 **가상머신(Guest OS) 전체를 팩트로 격리 암호화함** | CPU를 넘어, 거대한 연산을 처리하는 **외장 GPU 메모리와 버스를 통째로 팩트 암호화함** |
| 적용(최고 장점) | 보호 영역(TCB)이 극도로 좁아서 보안성은 최강이며 **핀셋처럼 정밀한 팩트 방어에 유리함** | 레거시 클라우드 앱을 아무런 소스코드 수정 없이(Lift & Shift) **그대로 이관할 때 팩트로 씀** | H100 같은 최신 칩에서 **대규모 AI 모델 학습 및 추론 데이터를 안전하게 보호할 때 팩트로 씀** |
| 치명적 한계 | 개발자가 코드를 하나하나 분리 설계해야 해서 **개발 난이도와 리팩토링 비용이 팩트로 헬임** | OS 전체를 보호하니까 보호 덩어리(TCB)가 너무 커져서 **공격 표면(털릴 구멍)이 팩트로 넓어짐** | 하드웨어 의존성이 심하고, CPU-GPU 간 통신 버스(PCIe) 병목 때문에 **최적화가 팩트로 빡셈** |

#### 한줄 요약

- 보안 끝판왕은 코드를 뜯어고치는 '엔클레이브', 편의성 끝판왕은 통째로 씌우는 '기밀 VM', AI는 무조건 '가속기 TEE'다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **TCB (신뢰 컴퓨팅 기반)**: 보안을 믿고 맡겨야 하는 범위 덩어리다. 이게 작을수록(엔클레이브) 해커가 찌를 구멍이 없고, 크면(기밀 VM) 공격 표면이 넓어져 위험하다.
- **RFC 9334 (RATS)**: 기밀 컴퓨팅 증명을 할 때, AWS 다르고 Azure 달라서 꼬이는 걸 막기 위해 만든 원격 증명 팩트 국제 표준 규격이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 클라우드 검증 서버 규격이 제각각이라 **원격 증명이 팩트로 꼬임** | 클라우드 벤더(AWS, Azure 등)마다 TEE 증명 방식과 토큰 포맷이 파편화되어 있음 | 원격 증명 국제 표준인 **IETF RFC 9334(RATS) 및 EAT 토큰 규격 팩트 강제 준수** | 이기종 클라우드 간 원격 증명 상호운용성 확보 및 벤더 종속성(Lock-in) 팩트 탈피 |
| 방공호 벽은 튼튼한데 **캐시나 전력 패턴을 읽어 비번을 팩트로 유추해 냄** | TEE 물리 경계 외부에 존재하는 캐시 메모리 타임이나 전력 소모 패턴 누출(부채널)을 노림 | 연산 시간을 항상 똑같이 맞추는 **Constant-time 코딩 및 캐시 플러시 팩트 강제 적용** | 캐시 적중률 및 시간차를 악용한 얍삽한 측채널(Side-channel) 팩트 공격 원천 방어 |
| 가속기(GPU)로 넘어갈 때 **메인보드 선(Bus)에서 데이터를 팩트로 가로챔** | CPU 방공호와 GPU 방공호 사이를 연결하는 고속도로(PCIe)가 평문이면 중간에 도청당함 | 데이터가 선을 탈 때도 하드웨어 레벨에서 암호화하는 **PCIe IDE(데이터 암호화) 팩트 적용** | 버스 스누핑(Bus Snooping) 등 하드웨어 간 물리적 도청 위협 완벽 차단 |

#### 한줄 요약

- 클라우드 이사 갈 때 표준(RFC 9334) 지키고, 소음/전력으로 비번 맞추는 꼼수(부채널) 막고, 메인보드 선(Bus)도 팩트로 잠가라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 클라우드 마이그레이션 시 **애플리케이션 엔클레이브**와 **기밀 VM**을 전략적으로 팩트 선택하고, 가장 취약한 '사용 중 데이터'를 지키기 위해 **TEE 하드웨어 격리**와 **원격 증명(RATS)** 을 강제하는 절대적 제로 트러스트 기조를 확립함

#### 한줄 요약

- 서버 주인도 내 데이터를 못 보게 만드는 궁극의 하드웨어 암호화다. AI와 클라우드 시대에 가장 필수적인 팩트 방패다.
