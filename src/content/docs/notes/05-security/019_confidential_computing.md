## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **기밀 컴퓨팅(Confidential Computing)**: 데이터가 스토리지에 저장되어 있을 때(Data at Rest)와 네트워크로 전송 중일 때(Data in Transit)뿐만 아니라, CPU와 RAM 메모리 상에서 실제 연산 처리되는 도중(Data in Use)에도 하드웨어 기반 신뢰 실행 환경(TEE)을 통해 메모리를 실시간 암호화하여 기밀성과 무결성을 보장하는 기술.
- **신뢰 실행 환경(Trusted Execution Environment, TEE)**: 메인 프로세서 내부에 호스트 OS, 하이퍼바이저, 루트 관리자 권한을 가진 사용자조차 내부 메모리를 열람하거나 변조할 수 없도록 하드웨어 레벨에서 격리된 보안 실행 공간.

</details>

- 정의/개념: CPU/GPU 하드웨어 메모리 암호화 엔진(Intel SGX/TDX, AMD SEV-SNP, ARM CCA, NVIDIA H100 TEE)과 **원격 증명(Remote Attestation / RFC 9334 RATS)** 메커니즘을 결합하여 클라우드 인프라 제공자(CSP)의 신뢰 없이도 안전하게 연산을 수행하는 **하드웨어 기반 제로 트러스트 컴퓨팅 아키텍처**
- 배경/필요성: 멀티 테넌트 퍼블릭 클라우드 환경에서 하이퍼바이저 침해, 콜드 부트 공격(Cold Boot Attack), 악의적 호스트 관리자에 의한 메모리 덤프 스누핑 등 '사용 중 데이터'의 평문 노출 취약점을 근본적으로 해결할 요구

#### 한줄 요약
- 하드웨어 TEE를 통해 CPU/RAM 메모리를 실시간 암호화하여 연산 중인 데이터의 기밀성을 완벽히 보호한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **신뢰 컴퓨팅 기반(Trusted Computing Base, TCB)**: 시스템의 보안성을 보장하기 위해 반드시 신뢰해야만 하는 하드웨어, 펌웨어, 소프트웨어 구성요소의 총 집합으로, TCB 범위가 좁을수록 공격 표면(Attack Surface)이 감소하여 보안성이 극대화됨.
- **원격 증명(Remote Attestation / RFC 9334)**: 격리된 TEE 내부의 해시 측정값(Measurement)과 하드웨어 제조사 서명을 외부 검증자(Verifier)에게 제출하여, 정품 하드웨어에서 인가된 코드가 무결하게 로드되었음을 암호학적으로 입증하는 절차.

</details>

- **하드웨어 강제 메모리 암호화 (Memory Encryption Engine)**: AES-XTS-128/256 엔진을 통해 CPU 캐시 외부로 나가는 모든 메모리 버스 트래픽을 온더플라이(On-the-Fly) 암호화
- **호스트 및 하이퍼바이저 불신 (Untrusted Host)**: 루트 권한을 가진 클라우드 OS나 가상화 하이퍼바이저가 침해되어도 게스트 워크로드 메모리 접근 원천 차단
- **RATS 기반 암호학적 신뢰 검증**: IETF RFC 9334 표준 EAT(Entity Attestation Token)를 통해 TEE 신원 및 코드 무결성 검증 완료 후에만 데이터 복호화 키 주입

#### 한줄 요약
- 하드웨어 메모리 암호화, 호스트 OS 불신 격리, TCB 최소화, RFC 9334 원격 증명을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **키 브로커 서비스(Key Broker Service, KBS)**: 원격 증명 검증기(Attestation Verifier)로부터 워크로드의 TEE 무결성 토큰이 정당하다고 확인된 경우에만, 해당 엔클레이브/CVM의 임시 공개키로 암호화(Key Wrapping)하여 데이터 암호키를 주입해 주는 보안 서비스.

</details>

```text
[ 데이터 소유자 (Client) ] ── (1. 암호화된 민감 데이터 및 알고리즘 배포)
                                      │
                                      ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ 퍼블릭 클라우드 호스트 서버 (Untrusted Host Infrastructure) ]                                  │
│  ├─ 호스트 OS / 하이퍼바이저 (KVM) ── (TEE 내부 메모리 접근 100% 하드웨어 차단)                  │
│  │                                                                                               │
│  └─ [ TEE 하드웨어 격리 도메인 (Intel TDX / AMD SEV-SNP CVM / SGX Enclave) ]                     │
│       ├─ AES 메모리 암호화 엔진 (MKTME / SME): 실시간 RAM 암호화/복호화                          │
│       ├─ 보호 워크로드 (AI 훈련 모델, 의료 분석 코드)                                            │
│       └─ 하드웨어 루트 키 기반 증명 생성기 (Attestation Report: 해시 측정값 $PCR$)               │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │
                                       ▼ [ 2. Attestation Report (하드웨어 서명 증거) 제출 ]
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ 원격 증명 검증기 (Attestation Verifier: RFC 9334) ] ── (3. 인텔/AMD Root CA 서명 및 해시 대조) │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │
                                       ▼ [ 4. Attestation Token 발급 및 키 해제 승인 ]
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ 키 브로커 서비스 (Key Broker Service, KBS) ] ──▶ [ 5. TEE 전용으로 Key Wrapping하여 주입 ]    │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 신뢰할 수 없는 클라우드 호스트 상의 TEE가 하드웨어 측정값을 검증기에 제출하여 승인을 받고, KBS로부터 안전하게 암호키를 주입받아 연산을 개시하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **하드웨어 TEE** | CPU 칩셋 내부에서 독립된 메모리 암호화 키를 관리하고 물리적 접근 차단 | Intel TDX / AMD SEV |
| **보호 워크로드** | TEE 엔클레이브 또는 기밀 가상머신(CVM) 내부에서 구동되는 민감 응용 프로그램 | Workload |
| **원격 증명 검증기** | TEE 증거의 제조사(Root CA) 서명 유효성 및 코드 해시(Measurement) 정책 심사 | RFC 9334 Verifier |
| **키 브로커 (KBS)** | 증명 검증을 통과한 유효한 TEE에 대해서만 암호화된 세션키(Wrapped Key) 프로비저닝 | Key Provisioning |
| **PCIe IDE 가속기** | CPU와 외장 GPU(NVIDIA H100) 간 PCIe 버스 전송 구간의 링크 암호화 집행 | PCIe 5.0 IDE |

#### 한줄 요약
- 하드웨어 TEE, 보호 워크로드, 원격 증명 검증기(Verifier), 키 브로커(KBS), PCIe IDE 가속기가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **키 래핑(Key Wrapping / RFC 3394)**: 키 브로커가 데이터를 복호화할 수 있는 마스터 대칭키를 TEE에 전달할 때, 오직 해당 TEE 인스턴스 내부의 임시 비대칭 개인키로만 복호화할 수 있도록 공개키로 캡슐화 암호화하여 전송하는 안전한 키 배포 기법.

</details>

```text
1. 클라우드 호스트 상에서 TEE(CVM/Enclave) 초기화 ➔ 하드웨어가 로드된 바이너리의 SHA-256 측정값(PCR) 산출
            │
            ▼
2. TEE가 칩셋 내부 고유 비밀키(Root Key)로 서명된 원격 증명 리포트(Attestation Report) 생성
            │
            ▼
3. 외부 독립 검증기(Verifier)가 리포트를 수신하여 CPU 제조사 신뢰 체인 및 코드 측정값의 불변 무결성 검증
            │
            ▼
4. 검증 성공 ➔ 검증기가 서명된 EAT 증명 토큰을 발급하고 키 브로커(KBS)로 전송
            │
            ▼
5. KBS가 TEE의 임시 공개키로 데이터 복호화 키를 래핑(Key Wrapping)하여 주입 ➔ TEE 내에서 안전한 연산 완수
```

**동작 원리**

1. **하드웨어 부팅 측정**: TEE 생성 시 하드웨어 레지스터가 게스트 코드와 펌웨어의 무결성 해시 기록
2. **증거 서명 생성**: 프로세서 다이(Die)에 퓨즈된 고유 개인키로 측정값에 전자서명 부착
3. **독립적 신뢰 평가**: 검증기가 공인된 정책(Golden Hash)과 TEE 리포트를 대조하여 백도어 변조 여부 판정
4. **암호화된 키 프로비저닝**: 호스트 OS나 네트워크 도청자가 가로챌 수 없도록 타겟 TEE 종단 암호화 적용
5. **격리 메모리 복호화**: 주입된 키를 바탕으로 TEE 내부에서만 평문으로 데이터가 로드되어 연산 집행

#### 한줄 요약
- 하드웨어 측정값 산출, Attestation 서명 리포트 생성, 독립 검증기 심사, EAT 토큰 발급, Key Wrapping 주입 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **기밀 컴퓨팅 3대 아키텍처 비교**: 최소 TCB의 애플리케이션 엔클레이브, 레거시 호환 기밀 가상머신(CVM), 대규모 AI 최적화 가속기 TEE의 비교.

</details>

| 비교 항목 | 애플리케이션 엔클레이브 (Intel SGX) | 기밀 가상머신 (AMD SEV-SNP / Intel TDX) | 가속기 TEE (NVIDIA H100 / Hopper) |
|:---|:---|:---|:---|
| **격리 단위** | **특정 프로세스/함수 단위 (Process)** | **가상머신 전체 (Guest OS + VM 전체)** | **외장 GPU 가속기 및 고대역 메모리(HBM)**|
| **TCB(신뢰 범위) 크기**| **최소 (애플리케이션 코드만 포함)** | 중간 (Guest OS 커널 포함으로 다소 큼) | 가속기 펌웨어 및 드라이버 포함 |
| **코드 리팩토링 필요성**| **필수 (전용 SDK로 코드 분리 개발)** | **불필요 (Lift & Shift 무수정 이전)** | 최소 수정 (CUDA 기밀 컴퓨팅 모드) |
| **주요 장점** | 가장 강력한 물리적 공격 표면 최소화 | 기존 클라우드 VM을 그대로 마이그레이션 | **초거대 LLM 모델 훈련/추론 실시간 가속** |
| **주요 적용 사례** | **암호화 키 관리(HSM), 생체 서명 인증** | **엔터프라이즈 ERP/DB 클라우드 이전** | **의료 AI 모델 학습, 기밀 LLM 서비스** |

#### 한줄 요약
- 엔클레이브는 최소 TCB 최고 보안, 기밀 VM은 무수정 클라우드 이전, 가속기 TEE는 대규모 AI 모델 기밀 처리에 최적화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **부채널 공격(Side-Channel Attack / 캐시 타이밍 공격)**: 공격자가 TEE 내부 메모리를 직접 읽지 못하더라도, CPU 공유 L3 캐시 접근 시간 차이(Flush+Reload), 분기 예측기 상태(Spectre), 전력 소모량 파형을 관측하여 TEE 내부의 암호키를 역산하는 하드웨어 취약점 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공유 CPU 캐시 접근 시간차를 악용한 공격자의 **부채널 타이밍(Side-Channel) 암호키 유출 공격** | **Constant-Time 알고리즘 구현, 캐시 파티셔닝(Intel CAT) 및 주기적 캐시 플러시** | 연산 시간 및 캐시 적중률 의존성 제거로 부채널 정보 누설 원천 차단 |
| CPU와 외장 GPU(가속기) 간의 PCIe 버스 라인을 물리적으로 도청하는 **버스 스누핑(Bus Snooping)** | **PCIe 5.0 IDE(Integrity and Data Encryption) 표준 하드웨어 링크 암호화** 강제 | 마더보드 물리 버스 전송 중 데이터 평문 노출 및 변조 위협 완벽 방어 |
| 이종 CSP(AWS, Azure, GCP) 간 TEE 증명 프로토콜 파편화로 인한 **원격 증명 연동 실패 및 벤더 종속** | **IETF RFC 9334 RATS 표준 아키텍처 및 공통 EAT(Entity Attestation Token)** 채택 | 멀티 클라우드 환경에서의 표준화된 원격 증명 상호운용성 100% 확보 |

#### 한줄 요약
- Constant-Time 코딩으로 부채널을 막고, PCIe IDE로 버스를 암호화하며, RFC 9334 RATS로 상호운용성을 보장한다.

## Ⅶ. 결론

- 클라우드 컴퓨팅 환경에서 '저장 중(At-Rest)', '전송 중(In-Transit)' 보안에 이어 마지막 남은 난제였던 '사용 중(In-Use)' 데이터 보안을 완성하는 **기밀 컴퓨팅(Confidential Computing) 아키텍처**는 제로 트러스트 인프라의 필수 요건이며, 실무 구현 시 **요구 보안 수준에 따른 엔클레이브와 CVM의 전략적 선택**, **RFC 9334 RATS 표준 원격 증명 파이프라인 구축**, **GPU 가속기 TEE 및 PCIe IDE 링크 암호화 결합**을 통합 추진하여 빈틈없는 엔드투엔드 데이터 보호 환경을 완성

#### 한줄 요약
- 하드웨어 TEE 메모리 암호화와 RFC 9334 원격 증명 및 PCIe IDE 링크 보안을 결합하여 완벽한 사용 중 데이터 보호를 실현한다.
