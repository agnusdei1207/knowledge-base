## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SOAR(Security Orchestration, Automation, and Response)**: 이기종 보안 솔루션(SIEM, 방화벽, EDR, 메일 게이트웨이, CTI)의 API를 단일 인터페이스로 연동·오케스트레이션하고, 사전 정의된 표준 대응 절차(Playbook)를 통해 반복적인 위협 분석, 인시던트 티켓 처리, 능동 차단 및 복구를 자동화하는 통합 보안 플랫폼.
- **보안 플레이북(Security Playbook / OASIS CACAO)**: 특정 위협 시나리오(예: 피싱 메일, 랜섬웨어 감염) 발생 시 수행해야 하는 조건 분기, CTI 조회, 승인 요청, 차단 API 호출 등 일련의 대응 절차를 시각적 워크플로 및 표준 코드로 정의한 실행 매뉴얼.

</details>

- 정의/개념: 가트너(Gartner) 정의에 따라 **보안 오케스트레이션 및 자동화(SOA)**, **보안 인시던트 대응 플랫폼(SIRP)**, **위협 인텔리전스 플랫폼(TIP)** 의 3대 역량을 결합하여 사고 대응 평균 시간(MTTR)을 분/초 단위로 단축하는 **차세대 보안 운영 자동화 아키텍처**
- 배경/필요성: 수동 관제 환경에서 발생하는 분석가의 알람 피로도(Alert Fatigue), 보안 전문 인력 부족(Skills Gap), 단편적인 수작업 대응으로 인한 침해 확산 골든타임 상실을 극복할 요구

#### 한줄 요약
- 이종 보안 장비 오케스트레이션과 표준 플레이북 자동화를 통해 초동 조사 및 능동 차단 시간을 획기적으로 단축한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인간 개입 통제(Human-in-the-Loop)**: 비즈니스 영향도가 큰 고위험 조치(예: 핵심 데이터베이스 서버 네트워크 격리, C-Level 계정 잠금)에 대해 완전 무인 자동화를 제한하고, 분석가의 명시적 승인(Approval)이 있어야만 후속 차단 단계를 실행하는 안전 통제 메커니즘.
- **조치 멱등성(Idempotency) & 롤백(Rollback)**: 동일한 차단 API를 네트워크 지연으로 다중 호출하더라도 시스템 상태가 일관되게 유지되도록 보장하고, 오차단 발생 시 즉시 이전 상태로 원상 복구하는 장애 방어 설계.

</details>

- **다기종 API 오케스트레이션**: RESTful API, SSH, Webhook을 통해 방화벽, EDR, 클라우드 IAM, ITSM(Jira/ServiceNow) 통합 제어
- **표준화된 플레이북 워크플로**: 위협 Triage $\rightarrow$ CTI 맥락 보강 $\rightarrow$ 위험도 평가 $\rightarrow$ 승인 분기 $\rightarrow$ 능동 격리 $\rightarrow$ 티켓 자동 종결
- **선택적 자동화 수준 제어**: 단순 반복 업무는 완전 무인화(Full-Auto), 고위험 조치는 반자동(Semi-Auto / Human-in-the-loop) 분기

#### 한줄 요약
- 이종 API 오케스트레이션, 표준 플레이북 자동화, Human-in-the-loop 안전 분기, 멱등성/롤백을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SOAR 3대 핵심 기둥(Gartner SOAR Framework)**:
  1. **SOA (보안 오케스트레이션/자동화)**: 이종 툴 간 상호작용 및 워크플로 자동 실행.
  2. **SIRP (보안 인시던트 대응 플랫폼)**: 인시던트 수명주기, 케이스 관리, SLA/KPI 관리.
  3. **TIP (위협 인텔리전스 플랫폼)**: 외부 CTI 피드 집계, 정제, IoC 상관분석 및 평판 보강.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 인시던트 인입 계층 (Trigger Ingestion) ]                           │
│  └─ SIEM 경보, EDR 탐지, 피싱 신고함, 클라우드 보안 알람 스트리밍       │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. SOAR 플레이북 오케스트레이션 엔진 (Core Engine) ]                  │
│  ├─ 1) 상태 머신 & 워크플로 실행기 (OASIS CACAO 2.0 Playbook Runner)    │
│  ├─ 2) 위협 인텔리전스 (TIP): VirusTotal / MISP 실시간 IoC 평판 조회   │
│  └─ 3) 정책 및 승인 분기점 (Human-in-the-loop Approval Portal)          │
└──────────────────┬──────────────────────────────────┬───────────────────┘
                   │ (완전 자동 실행)                 │ (관리자 승인 완료 후)
                   ▼                                  ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. API 커넥터 및 조치 계층 (Action Execution Layer) ]                 │
│  ├─ 엔드포인트 격리: EDR API 호출 ➔ 감염 호스트 네트워크 분리          │
│  ├─ 경계망 차단: NGFW / WAF API 호출 ➔ 악성 C2 IP 블랙리스트 등록       │
│  ├─ 계정 제어: Active Directory / Okta API ➔ 침해 계정 비활성화 및 세션 무효화│
│  └─ ITSM 케이스 갱신: ServiceNow 티켓 상태 'Closed Resolved' 자동 업데이트│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 인입된 인시던트가 플레이북 엔진에서 CTI 보강과 승인 분기를 거쳐, API 커넥터를 통해 엔드포인트/방화벽/계정 제어를 자동 완수하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **플레이북 엔진** | OASIS CACAO 표준 기반 워크플로를 해석하고 상태 머신에 따라 단계별 작업 실행 | Workflow Engine |
| **API 커넥터/앱 (App)** | 300개 이상의 타사 보안 솔루션과 사전 정의된 API 인터페이스로 상호 통신 | App Integration |
| **TIP 맥락 보강기** | 인입된 IP, 도메인, 파일 해시를 CTI 피드와 대조하여 악성 여부 자동 채점 | Threat Intel |
| **인간 승인 포털** | 고위험 차단 액션 실행 전 Slack, Teams, Email 기반 1-클릭 승인 인터페이스 제공 | Approval Gateway|
| **케이스 관리 시스템 (SIRP)**| 인시던트의 전 생애주기 타임라인, 증적, SLA 준수율, 감사 로그 기록 관리 | Case Management |

#### 한줄 요약
- 플레이북 엔진, API 커넥터, TIP 맥락 보강기, 인간 승인 포털, 케이스 관리(SIRP)가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **피싱 메일 대응 표준 플레이북 시나리오**:
  1. 사용자 피싱 신고 접수 $\rightarrow$ 2. 이메일 헤더/첨부파일 파싱 $\rightarrow$ 3. 샌드박스 악성 분석 및 CTI 평판 조회 $\rightarrow$ 4. 악성 확정 시 사내 전 메일함에서 동일 메일 일괄 삭제 $\rightarrow$ 5. 방화벽 C2 도메인 차단 및 사용자 통보.

</details>

```text
1. [사건 인입] SIEM에서 "의심스러운 외부 C2 연결 탐지" 인시던트가 SOAR 플랫폼으로 실시간 전송
            │
            ▼
2. [CTI 자동 보강] 플레이북이 목적지 IP/URL을 추출하여 VirusTotal 및 MISP에 REST API 질의 ➔ [악성 판정]
            │
            ▼
3. [위험도 평가 및 분기]
    ├─ [일반 PC 단말]: EDR API를 호출하여 호스트 네트워크 즉시 자동 격리 (Full-Auto)
    └─ [핵심 서버/DB]: Slack 웹훅으로 SOC 팀장에게 승인 요청 발송 (Human-in-the-loop) ➔ [승인 완료]
            │
            ▼
4. [오케스트레이션 차단 실행]
    ├─ 차세대 방화벽(NGFW) API 호출 ➔ C2 IP 인바운드/아웃바운드 차단 룰 추가
    ├─ EDR API 호출 ➔ 악성 프로세스 강제 종료 및 레지스트리 런키 제거
    └─ Active Directory API 호출 ➔ 해당 사용자 세션 강제 만료 및 비밀번호 리셋
            │
            ▼
5. [완료 검증 및 증적 기록] 방화벽 룰 적용 상태 재조회(멱등성 검증) ➔ ITSM 티켓에 증적 첨부 후 자동 종결
```

**동작 원리**

1. **이벤트 트리거링**: Webhook 또는 메시지 큐를 통한 밀리초 단위 인시던트 수신
2. **무인 Triage**: 사전 구축된 인텔리전스 커넥터를 병렬 호출하여 10초 내 증거 수집
3. **영향도 기반 위험 분기**: 사내 자산 레벨에 따라 자동 조치와 인간 승인 경로를 동적 분기
4. **다중 시스템 일괄 제어**: 단일 플레이북 실행으로 네트워크, 엔드포인트, 계정을 동시 통제
5. **폐쇄 루프 검증**: API 호출 성공 응답 수신 및 정책 반영 여부를 재확인하여 실행 실패 방지

#### 한줄 요약
- 인시던트 인입, CTI 자동 보강, 위험도 승인 분기, 다중 API 일괄 차단, 완료 검증 및 티켓 종결 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SOAR 자동화 실행 3대 방식 비교**: 수동 대응(Manual), 인간 승인 반자동(Human-in-the-loop), 완전 무인 자동화(Fully Automated)의 비교.

</details>

| 비교 항목 | 수동 대응 (Manual Operations) | 인간 승인 반자동 (Human-in-the-Loop) | 완전 무인 자동화 (Fully Automated) |
|:---|:---|:---|:---|
| **조사 및 분석 주체** | **보안 분석가 (수동 로그 검색)** | **SOAR 로봇 (CTI 평판 자동 보강)** | **SOAR 로봇 (전 과정 자동 분석)** |
| **차단 조치 실행 주체**| **분석가가 방화벽 GUI 수동 접속** | **분석가 1-Click 승인 ➔ 로봇 실행** | **SOAR 로봇 (사전 정의 룰 기반 즉시 차단)**|
| **평균 대응 시간 (MTTR)**| **수십 분 ~ 수 시간 (지연 큼)** | **수 분 이내 (승인 즉시 완결)** | **수 초 ~ 수 밀리초 (초고속 실시간 대응)** |
| **오조치(오차단) 위험도**| 낮음 (사람이 맥락을 확인) | **극도로 낮음 (로봇의 속도 + 사람의 검증)**| 오탐 룰셋 배포 시 전사 업무 마비 위험 |
| **주요 권장 적용 영역** | **고도화된 신종 APT 공격, 표적 침해**| **핵심 서버 격리, 임원 계정 잠금** | **스팸/피싱 메일 차단, 단순 악성 IP 격리** |

#### 한줄 요약
- 수동 대응은 신종 APT 포렌식용, 인간 승인은 고위험 자산 격리용, 완전 무인은 단순 반복 알람 대량 처리용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OASIS CACAO 2.0 (Collaborative Automated Operation of Anomalies, Incidents, and Risks)**: 보안 플레이북의 벤더 종속성을 제거하고 표준 JSON 스키마를 통해 조직 간, 도구 간 플레이북을 상호 교환하고 재사용할 수 있도록 제정된 국제 표준 규격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 벤더 종속적 스크립트로 작성된 플레이북으로 인한 **보안 장비 교체 시 전면 재개발 오버헤드** | **OASIS CACAO 2.0 표준 플레이북 스펙 도입 및 공통 API 어댑터 인터페이스 추상화** | 이기종 보안 솔루션 간 플레이북 100% 재사용 및 벤더 락인(Lock-in) 방지 |
| 완전 무인 자동화 플레이북 오류로 인해 **정상 ERP 데이터베이스 서버가 네트워크에서 차단되는 대형 사고** | **고위험 자산에 대한 Human-in-the-loop 승인 강제, 조치 멱등성 및 1-Click 롤백 로직 구현** | 오조치로 인한 비즈니스 중단 0% 달성 및 사고 발생 시 즉각 원상 복구 보장 |
| 방화벽/EDR 장비의 네트워크 일시 단절로 인한 **API 차단 명령 유실 및 대응 실패** | **비동기 메시지 큐(Kafka/RabbitMQ) 기반의 지수 백오프(Exponential Backoff) 재시도 엔진** 탑재 | 일시적 네트워크 장애 시에도 차단 명령 유실률 0% 및 최종 일관성(Eventual Consistency) 달성 |

#### 한줄 요약
- CACAO 표준으로 락인을 방지하고, Human-in-the-loop과 롤백으로 오조치를 막으며, 큐/재시도로 명령 유실을 방지한다.

## Ⅶ. 결론

- 매일 폭증하는 보안 경보와 숙련된 분석 인력 부족의 간극을 해소하는 **SOAR 아키텍처**는 현대 SOC의 필수 핵심 인프라이며, 실무 구현 시 **OASIS CACAO 기반 표준 플레이북 구축**, **위험도에 따른 Human-in-the-loop 및 완전 무인화의 전략적 분기**, **멱등성 및 롤백 설계를 통한 비즈니스 연속성 확보**를 통합 추진하여 초 단위의 신속하고 안전한 사이버 침해사고 대응 체계를 완성

#### 한줄 요약
- 이종 API 오케스트레이션과 표준 CACAO 플레이북 및 인간 승인 통제를 결합하여 MTTR을 초 단위로 단축한다.
