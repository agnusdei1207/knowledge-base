## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **보안 오케스트레이션•자동화 및 대응(Security Orchestration, Automation and Response, SOAR)**: 보안 도구를 연결하여 사건 조사•승인•조치 절차를 자동화하는 플랫폼이다.
- **플레이북**: 사건의 조사•판단•승인•조치 순서와 분기 조건을 정의한 절차이다.

</details>

- 정의/개념: **SOAR**는 보안 도구를 연결해 **플레이북** 기반 조사•조치를 자동화하는 플랫폼이다.
- 배경/필요성: 수동 처리만으로는 대량 경보의 대응 지연과 절차 누락을 방지할 수 없다.

#### 한줄 요약
- 경보를 받으면 정해진 순서로 정보를 조회하고 위험한 조치는 사람의 승인을 받은 뒤 실행한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **보안 정보•이벤트 관리(Security Information and Event Management, SIEM)**: 로그에서 경보와 조사 근거를 생성하는 플랫폼이다.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: SOAR가 조회•차단•격리 기능을 호출하는 연동 규격이다.

</details>

- **SIEM**과 보안 도구의 **API**를 오케스트레이션한다.
- 반복 대응 절차를 **플레이북**으로 자동화한다.
- 위험도에 따라 자동•승인•수동 실행을 분기한다.

#### 한줄 요약
- 방화벽 차단 실패를 전체 성공으로 오인하지 않아야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **상태 머신**: 사건의 접수•분석•승인•조치•종료 상태와 허용 전이를 관리하는 구조이다.
- **큐**: 처리할 API 요청을 순서대로 보관해 장애•과부하 때 유실을 줄이는 대기열이다.
- **롤백**: 자동 조치 실패나 오조치 때 이전 상태로 되돌리는 복구 절차이다.

</details>

```text
SOAR 기능 구조
├─ 사건•상태 머신
├─ 보강•판단
├─ 승인•감사
├─ 조치 커넥터•큐
└─ 재시도•롤백
```

가지의 의미: 사건 판단부터 승인•실행•실패 복구까지의 정적 기능 구성을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 사건•상태 머신 | **상태 머신**으로 사건•플레이북 전이 관리 |
| 보강•판단 | 자산•위협 정보로 위험도 판정 |
| 승인•감사 | 고위험 조치 승인•실행 이력 보관 |
| 조치 커넥터•큐 | 최소 권한 **API** 호출과 **큐**의 요청 보존 |
| 재시도•롤백 | **롤백**으로 부분 실패 복구•수동 전환 |


#### 한줄 요약

- 자동 명령을 보낸 뒤 대상 시스템의 실제 상태를 확인해야 사건을 완료로 닫을 수 있다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **멱등성(Idempotency)**: 같은 조치 요청이 반복돼도 결과가 한 번 실행한 상태와 같게 유지되는 성질이다.
- **완료 증적**: 명령 응답뿐 아니라 대상 시스템의 실제 상태가 원하는 결과로 바뀌었음을 확인한 기록이다.
- **사건 보강•위험도 판정**: 자산•위협 정보로 사건의 영향과 확신 수준을 평가하는 단계이다.
- **승인•정책 분기**: 위험도•업무 영향•가역성에 따라 자동•승인•수동 실행을 선택하는 단계이다.
- **멱등 조치 실행**: 최소 권한 API로 반복해도 같은 결과가 되는 조치를 수행하는 단계이다.
- **실제 상태 검증**: 대상 시스템을 다시 조회해 조치가 원하는 상태로 완료됐는지 확인하는 단계이다.
- **재시도•롤백 결정**: 부분 실패를 재시도하거나 이전 상태로 복구하고 필요하면 수동 대응으로 넘기는 단계이다.

</details>

```text
사건•정보 유입
        │
        ▼
1. 사건 보강•위험도 판정
        │
        ▼
2. 승인•정책 분기
        ├─ 거부•고위험 ── 수동 대응
        └─ 승인•저위험
                │
                ▼
3. 멱등 조치 실행
        │
        ▼
4. 실제 상태 검증
        ├─ 성공 ── 완료 증적 반환
        └─ 부분 실패
                │
                ▼
5. 재시도•롤백 결정
        ├─ 재시도 ── 실제 상태 재검증
        └─ 롤백 실패 ── 수동 대응 전환
```

### 동작 원리

1. **사건 보강•위험도 판정**: 자산•위협 정보로 영향을 평가한다.
2. **승인•정책 분기**: 위험도•가역성에 따라 실행 방식을 선택한다.
3. **멱등 조치 실행**: **멱등성**을 갖춘 최소 권한 API 조치를 수행한다.
4. **실제 상태 검증**: 대상 시스템에서 **완료 증적**을 확인한다.
5. **재시도•롤백 결정**: **롤백**하거나 수동 대응으로 전환한다.


#### 한줄 요약

- 처음부터 자동 차단하지 않고 조회와 권고부터 검증해 신뢰가 쌓일 때 권한을 넓힘이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **자동화 수준**: 조치의 신뢰도•업무 영향•가역성에 따라 수동, 사람 승인, 무인 자동화로 나눈 실행 등급이다.
- **수동 대응**: 분석가가 조사부터 조치까지 전 과정을 직접 수행하는 방식이다.
- **사람 승인 자동화**: 자동 보강•판단 후 사람이 승인한 조치만 실행하는 방식이다.
- **무인 자동화**: 사전 조건을 충족한 저영향•고신뢰 조치를 사람 승인 없이 실행하는 방식이다.

</details>

| SOAR 실행 방식 | 수동 대응 | 사람 승인 자동화 | 무인 자동화 |
|:---|:---|:---|:---|
| 적용 기준 | 복잡•고영향 비정형 사건 | 가역적 업무 영향 조치 | 저영향•반복•고신뢰 업무 |
| 핵심 특징 | **수동 대응**으로 전 과정 실행 | **사람 승인 자동화** | **무인 자동화** |
| 한계 | 대응 지연•분석가 피로 | 승인 병목 | 대량 오조치 확산 |

> 요약: 신뢰•영향•가역성 기반 자동화 수준 결정하는 것이 핵심이다.

#### 한줄 요약

- 메일 조회는 자동화해도 핵심 관리자 계정 폐기는 사람이 확인하게 만드는 식으로 단계를 나눔이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **구조화 정보 표준 발전 기구(Organization for the Advancement of Structured Information Standards, OASIS)**: 개방형 정보 표준을 개발하는 조직이다.
- **자동화된 행동 과정 협업(Collaborative Automated Course of Action Operations, CACAO) 2.0**: 보안 플레이북의 구조•워크플로•명령•서명을 정의한 표준이다.
- **미국 국립표준기술연구소(National Institute of Standards and Technology, NIST)**: 미국의 기술 표준과 지침을 개발하는 기관이다.
- **특별 간행물(Special Publication, SP) 800-61 Rev. 3**: 사고 대응을 위험 관리 활동에 통합하는 지침이다.
- **통합 자원 위치 지정자(Uniform Resource Locator, URL)**: 웹 자원의 위치를 나타내는 주소이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 플레이북 상호운용 | **OASIS** **CACAO 2.0** 적용 | 도구 간 절차 공유성 확보 |
| 사고 대응 책임 | **NIST** **SP 800-61 Rev. 3** 연계 | 탐지•복구 과정 통합 |
| 자동 조치 오작동 | 승인•**멱등성**•**롤백** 설계 | 대량 오조치 확산 방지 |

#### 한줄 요약

- SOAR는 신고 메일의 **URL**•첨부파일 평판을 자동 조회하고, 분석가가 악성으로 승인하면 같은 메일을 전사 메일함에서 격리한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **안전한 자동화**: 저영향•고신뢰 조치부터 시작해 검증 결과에 따라 권한을 단계적으로 확대하는 원칙이다.

</details>

- **안전한 자동화**와 **자동화 수준**에 따라 고영향은 **수동 대응**, 가역 조치는 **사람 승인 자동화**, 저영향•고신뢰는 **무인 자동화**를 적용한다.

#### 한줄 요약

- SOAR는 안전한 조치부터 자동화해야 한다.
