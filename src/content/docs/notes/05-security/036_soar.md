## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **보안 오케스트레이션•자동화 및 대응(Security Orchestration, Automation and Response, SOAR)**: 다양한 보안 이종 솔루션을 연계하여 침해사고 조사•승인•대응 절차를 오케스트레이션하고 자동화하는 플랫폼.
- **플레이북(Playbook)**: 침해사고의 수집, 분석, 조건 분기, 인간 승인 및 조치 단계를 표준 워크플로로 정의한 실행 지침.

</details>

- 정의/개념: 플레이북으로 조사•조치를 자동화하는 **SOAR**
- 배경/필요성: 수동 경보 처리로는 **대량 사건•대응 지연** 통제 불가

#### 한줄 요약

- 경보 발생 시 사전 정의된 플레이북에 따라 정보 수집과 위험도 분기, 승인 통제를 수행함.

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **보안 정보•이벤트 관리(Security Information and Event Management, SIEM)**: 중앙 로그 집계 및 상관분석을 통해 탐지 경보를 발생시키는 상위 관제 시스템.
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: SOAR가 이종 보안 장비(방화벽, EDR, 메일 등)에 조회 및 차단 명령을 자동 전송하기 위한 연동 규약.

</details>

- **SIEM** 탐지 경보와 보안 장비 **API** 인터페이스의 오케스트레이션 연계.
- 반복적인 사건 조사 및 대응 프로세스의 **플레이북(Playbook)** 기반 자동화.
- 위험도 및 역가역성에 맞춘 무인 자동화, 사람 승인, 수동 대응 단계별 분기 통제.

#### 한줄 요약

- 솔루션 간 연동 오케스트레이션과 위험도 기반 인간 개입 단계 분기를 제공함.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **상태 머신(State Machine)**: 사건의 발생, 분석, 승인, 조치 완료 및 폐기 상태 간 표준 전이 규칙을 제어하는 엔진.
- **큐(Queue / Task Queue)**: 이종 시스템 API 호출 연동 시 병목 및 일시적 장애에 대비하여 조치 요청을 보존하는 대기열.
- **롤백(Rollback Procedure)**: 오조치 발생이나 자동 실행 실패 시 변경된 통제 정책을 직전 정상 상태로 복구시키는 회복 기능.

</details>

```text
SOAR 기능 구조
├─ 사건•상태 머신
├─ 보강•판단
├─ 승인•감사
├─ 조치 커넥터•큐
└─ 재시도•롤백
```

가지의 의미: 사건 판단부터 승인•실행•실패 복구까지의 정적 기능 구성을 표현.

| 구성요소 | 책임 |
|:---|:---|
| 사건•상태 머신 | **상태 머신** 기반 사건 생명주기 및 워크플로 전이 통제 |
| 보강•판단 | 자산 중요도 및 CTI 기반 위험도 분석•판정 |
| 승인•감사 | 고위험 조치의 인간 승인 절차 제어 및 감사 로그 보존 |
| 조치 커넥터•큐 | 최소 권한 **API** 커넥터 호출 및 **큐(Queue)** 요청 보존 |
| 재시도•롤백 | **롤백** 기능 기반 트랜잭션 예외 처리 및 수동 대응 이관 |

#### 한줄 요약

- 상태 머신과 커넥터를 통해 자동 명령 전달 후 대상 시스템의 조치 상태 완료를 검증함.

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **멱등성(Idempotency)**: 동일한 조치 명령을 여러 번 실행해도 시스템의 최종 결과 상태가 한 번 실행했을 때와 동일하게 유지되는 성질.
- **완료 증적(Completion Evidence)**: API 단순 반환값을 넘어 실제 Target 장비의 정책 상태 변경이 완료되었음을 입증하는 수집 결과.
- **사건 보강•위험도 판정(Enrichment & Risk Triage)**: 자산 맥락 및 위협 인텔리전스를 연계하여 사건 영향과 확신 수준을 산정하는 단계.
- **승인•정책 분기(Approval & Policy Branching)**: 조치 위험도, 가역성 및 서비스 영향도에 따라 실행 모드를 결정하는 단계.
- **멱등 조치 실행(Idempotent Action Execution)**: 멱등성이 보장된 최소 권한 API를 호출하여 제어 조치를 수행하는 단계.
- **실제 상태 검증(State Verification)**: 대상 시스템을 재조회하여 설정 변경 및 차단 조치의 적용 완료를 확인하는 단계.
- **재시도•롤백 결정(Retry & Rollback Decision)**: 부분 실패 시 재시도하거나 롤백을 수행하고, 실패 지속 시 수동 대응으로 전환하는 단계.

</details>

```text
사건•정보 유입
        │
        ▼
1. 사건 보강•위험도 판정
        │
        ▼
2. 승인•정책 분기
        ├─ 거부•고위험 ── 수동 대응
        └─ 승인•저위험
                │
                ▼
3. 멱등 조치 실행
        │
        ▼
4. 실제 상태 검증
        ├─ 성공 ── 완료 증적 반환
        └─ 부분 실패
                │
                ▼
5. 재시도•롤백 결정
        ├─ 재시도 ── 실제 상태 재검증
        └─ 롤백 실패 ── 수동 대응 전환
```

### 동작 원리

1. **사건 보강•위험도 판정**: 자산 중요도 및 CTI 기반 영향도 평가.
2. **승인•정책 분기**: 가역성 및 영향도 기반 실행 방식(무인/승인/수동) 분기.
3. **멱등 조치 실행**: **멱등성(Idempotency)** 기반 최소 권한 API 제어 조치 수행.
4. **실제 상태 검증**: 대상 시스템의 **완료 증적** 재조회 및 수집.
5. **재시도•롤백 결정**: 트랜잭션 오류 시 **롤백** 또는 담당자 수동 이관 처리.

#### 한줄 요약

- 정보 수집 및 위험도 판정 후 멱등성이 확보된 조치를 수행하며 실패 시 롤백을 처리함.

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **자동화 수준(Automation Level)**: 조치 위험도 및 비즈니스 영향도에 따라 정의되는 실행 자동화 단계(Low/Medium/High Level).
- **수동 대응(Manual Incident Response)**: 분석가가 전체 조사 및 조치 과정을 개별 통제하고 결정하는 100% 인적 대응 방식.
- **사람 승인 자동화(Human-in-the-loop Automation)**: 분석 및 정보 수집은 자동 수행하되, 차단 조치는 담당자 승인 후 실행하는 방식.
- **무인 자동화(Fully Automated Response / Fully-Autonomous)**: 사전에 정의된 고신뢰 저위협 경보에 대해 사람 개입 없이 즉시 자동 차단을 수행하는 방식.

</details>

| SOAR 실행 방식 | 수동 대응 | 사람 승인 자동화 | 무인 자동화 |
|:---|:---|:---|:---|
| 적용 기준 | 복잡•고영향 비정형 사건 | 가역적 업무 영향 조치 | 저영향•반복•고신뢰 업무 |
| 핵심 특징 | **수동 대응**으로 전 과정 실행 | **사람 승인 자동화** | **무인 자동화** |
| 한계 | 대응 지연•분석가 피로 | 승인 병목 | 대량 오조치 확산 |

> 요약: 위협 신뢰도, 업무 영향도 및 가역성에 기반한 차등 자동화 수준 적용.

#### 한줄 요약

- 사건의 복잡성과 영향도에 따라 수동 대응, 사람 승인 자동화, 무인 자동화로 나누어 운영함.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **구조화 정보 표준 발전 기구(Organization for the Advancement of Structured Information Standards, OASIS)**: SOAR 플레이북 표준화(CACAO) 등을 이끄는 국제 기구.
- **자동화된 행동 과정 협업(Collaborative Automated Course of Action Operations, CACAO 2.0)**: SOAR 플레이북의 워크플로, 명령, 승인 및 서명 명세를 규정한 국제 표준.
- **미국 국립표준기술연구소(National Institute of Standards and Technology, NIST)**: 보안 지침을 발간하는 미국 정보보호 정부 기관.
- **특별 간행물(Special Publication, SP 800-61 Rev. 3)**: 컴퓨터 보안 사건 대응 프로세스 표준 지침.
- **통합 자원 위치 지정자(Uniform Resource Locator, URL)**: 악성 웹사이트 여부를 검증하기 위한 웹 경로 주소.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 플레이북 상호운용 | **OASIS CACAO 2.0** 적용 | 도구 간 절차 공유성 확보 |
| 사고 대응 책임 | **NIST SP 800-61 Rev. 3** 연계 | 탐지•복구 과정 통합 |
| 자동 조치 오작동 | 승인•**멱등성**•**롤백** 설계 | 대량 오조치 확산 방지 |

#### 한줄 요약

- 신고 메일의 URL 평판을 자동 조회 후 위험도가 입증되면 분석가 승인으로 전사 격리를 자동 집행함.

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **안전한 자동화(Safe Automation Principles)**: 무차별 전면 자동화를 지양하고 정보 보강(Enrichment)부터 시작하여 단계적으로 차단 통제 권한을 확장하는 설계 원칙.

</details>

- **안전한 자동화** 원칙에 따라 고영향 조치는 **수동 대응**, 가역 조치는 **사람 승인 자동화**, 저위협 고신뢰 업무는 **무인 자동화** 차별화 적용.

#### 한줄 요약

- **영향도•가역성•신뢰도**에 따라 자동화 수준 결정
