## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디스크 이미징(Disk Imaging / Bit-stream Acquisition)**: 피압수 저장매체(HDD, SSD, USB 등)의 논리적 파일 구조뿐만 아니라 부트 레코드, 파티션 테이블, 할당 영역, 비할당 영역(Unallocated Space), 슬랙 공간(Slack Space)을 포함한 물리적 섹터 전체를 0과 1의 비트 단위로 1:1 완벽하게 사본 파일(E01, RAW, DD 등)로 복제하는 포렌식 획득 기술.
- **파일 단위 복사와 비트스트림 이미징 간의 차이 결함(File Copy vs Bit-stream Defect)**: 일반 파일 복사(Ctrl+C/V) 방식을 사용할 경우, 파일 메타데이터(생성/수정/접근 시간)가 현재 시점으로 오염되고, 피의자가 삭제한 데이터가 잔존하는 비할당 영역 및 슬랙 공간을 복제하지 못해 핵심 증거가 누락되는 구조적 결함.

</details>

- 정의/개념: 원본 매체의 증거 훼손을 원천 방어하기 위해 **하드웨어 쓰기 방지 장치(Write Blocker) 연결 $\rightarrow$ 전 섹터 1:1 비트스트림 이미징 $\rightarrow$ 원본 및 사본 암호학적 해시(SHA-256) 생성 및 대조 $\rightarrow$ 배드섹터(Bad Sector) 오류 로그 문서화 $\rightarrow$ 연계보관성(Chain of Custody) 갱신** 을 집행하는 **저장매체 무결성 보증 아키텍처**
- 배경/필요성: 디지털 증거가 법정에서 채택되기 위한 필수 요건인 '증거의 동일성(Identity)'과 '무결성(Integrity)'을 수학적으로 입증하고, SSD TRIM 등 저장장치 고유 특성에 대응할 요구

#### 한줄 요약
- 쓰기 방지 장치 하에서 1:1 비트스트림 복제를 수행하고 SHA-256 해시값 일치를 통해 증거 무결성을 입증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **디스크 이미징의 핵심 메커니즘**:
  - **하드웨어 쓰기 방지 (Hardware Write Blocker)**: OS가 마운트 시 디스크에 로그나 임시파일을 쓰는 행위를 물리적 브리지 컨트롤러에서 차단.
  - **비할당 영역 획득 (Unallocated Space Acquisition)**: 파일시스템에서 삭제 마킹되었으나 실제 데이터 블록이 지워지지 않은 잔여 데이터 수집.
  - **암호학적 해시 일치 ($H_{orig} = H_{image}$)**: 원본 디스크의 전체 비트열 해시와 이미징 결과 파일의 해시가 완벽히 일치함을 증명.

</details>

- **완전한 비트 단위 복제(Bit-stream Exact Copy)**: 논리적 파일뿐만 아니라 볼륨 슬랙, 파일 슬랙, 미할당 클러스터까지 1섹터의 오차 없이 복제
- **수학적 무결성 및 조작 불가능성 입증**: FIPS PUB 180-4 표준 SHA-256 해시를 산출하여 이미징 과정 중 1비트의 변조도 없었음을 객관적으로 보증
- **오류 기록의 투명성(Transparency)**: 물리적 스크래치나 배드섹터(Bad Sector)로 인해 읽기 실패한 섹터의 위치(LBA)와 대체 블록 처리 로그를 포렌식 이미지 메타데이터에 명시

#### 한줄 요약
- 비할당 영역 포함 전 섹터 복제, 하드웨어 쓰기 방지, SHA-256 해시 무결성 검증, 배드섹터 로그 투명성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **디스크 이미징 4대 핵심 컴포넌트**:
  1. **Source Storage Device (원본 매체)**: 피의자 PC/서버에서 분리된 원본 물리 드라이브.
  2. **Hardware Write Blocker (쓰기 방지기)**: 원본 매체의 Write Command 신호를 하드웨어 레벨에서 차단.
  3. **Forensic Workstation & Imager**: FTK Imager, Guymager 등 비트스트림 덤프 엔진.
  4. **Target Image File & Hash Certificate**: E01/RAW 사본 파일 및 SHA-256/MD5 해시 대조 증명서.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 피압수 원본 저장매체 (Original Source Device: HDD / NVMe / USB) ]   │
│  └─ 모델명, 일련번호(S/N), LBA 전체 섹터 수 현장 사진 및 대장 기록     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (물리적 SATA/NVMe 케이블 연결)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 하드웨어 쓰기 방지 장치 (Hardware Write Blocker: 물리적 차단) ]     │
│  ├─ Write Command 신호 전기적 차단 ➔ [ 원본 디스크 읽기 전용(Read-only) 강제]│
│  └─ [ NIST CFTT 공인 검증 통과 브리지 컨트롤러 탑재 (오염 0% 보증) ]    │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (읽기 신호 전송 및 데이터 스트림 수신)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 포렌식 워크스테이션 및 이미징 엔진 (Forensic Imaging Engine) ]     │
│  ├─ 1:1 비트스트림 덤프 ➔ 비할당 영역, 파일 슬랙, 배드섹터 로그 기록   │
│  ├─ [ 포렌식 사본 파일 생성 (Expert Witness Format: E01 / RAW DD) ]    │
│  └─ [ 암호학적 해시 산출: $H(\text{Source}) = H(\text{Image}) = \text{SHA-256}$ ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (원본 금고 봉인 & 사본 랩실 인계)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 연계보관성 대장 및 사본 분석 (Chain of Custody & Lab Analysis) ]   │
│  └─ [ 해시 증명서 첨부 연계보관부 작성 ➔ 랩실에서 사본 파일 복원 수술 ]  │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 원본 매체가 쓰기 방지기를 거쳐 워크스테이션에서 E01 비트스트림 사본으로 이미징되고 해시 검증 후 보관되는 구조

| 구성요소 | 핵심 역할 및 기능 | 주요 기술 및 규격 | 비고 |
|:---|:---|:---|:---|
| **원본 저장매체** | 디지털 증거가 저장된 물리적 하드웨어 | HDD, SSD, NVMe, SD카드 | Source |
| **쓰기 방지 장치** | 호스트 OS로부터의 Write/Delete 명령을 하드웨어적으로 원천 차단 | Tableau T8u, WiebeTech UltraDock | Hardware |
| **이미징 소프트웨어** | 섹터 단위 순차 읽기 및 압축/분할 포렌식 이미지 포맷 생성 | FTK Imager, Guymager, X-Ways, `dd` | Software |
| **포렌식 이미지 포맷** | 디스크 비트열과 함께 사건 정보, 해시값, 수사관 메타데이터를 캡슐화 | E01 (Expert Witness), RAW/DD, AFF | Image Format|
| **암호 해시 엔진** | 덤프 전/후 원본과 사본의 일치성을 수학적으로 증명하는 알고리즘 | SHA-256, SHA-512 (FIPS PUB 180-4) | Verification|

#### 한줄 요약
- 원본 매체, 하드웨어 쓰기 방지 장치, 이미징 소프트웨어, E01 이미지 포맷, SHA-256 해시 엔진으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **디스크 이미징 5단계 표준 절차**:
  1. 원본 매체 물리적 식별 및 쓰기 방지 장치 결착
  2. 원본 매체 사전 해시(Pre-acquisition Hash) 산출
  3. 비트스트림 이미징 수행 및 배드섹터 로깅
  4. 사본 이미지 사후 해시(Post-acquisition Hash) 산출 및 대조
  5. 해시 검증서 발행, 원본 봉인 및 연계보관부(CoC) 작성

</details>

```text
1. [원본 식별 및 쓰기 방지 결착]
    ├─ 압수 하드디스크의 라벨, 일련번호(S/N), 인터페이스(SATA 3.0) 기록
    └─ [하드웨어 Write Blocker에 원본 연결 ➔ 워크스테이션 포렌식 툴 마운트]
            │
            ▼
2. [사전 해시 산출 및 이미징 개시]
    ├─ 원본 디스크 전체 LBA 섹터 대상 SHA-256 사전 해시 계산
    └─ [E01 포맷으로 1:1 비트스트림 이미징 시작 (블록 단위 검증)]
            │
            ▼
3. [배드섹터 처리 및 로깅]
    ├─ 물리적 손상 섹터 발견 시 0으로 대체(Zero-fill)하고 해당 섹터 번호 로그 기록
    └─ [정상 섹터와 오류 섹터의 전수 이미징 완료]
            │
            ▼
4. [사후 해시 대조 및 검증]
    ├─ 생성된 E01 이미지 파일의 SHA-256 해시값 산출
    └─ [대조 검증: $\text{Pre-Hash}(\text{Source}) = \text{Post-Hash}(\text{Image})$ ➔ 동일성 100% 확인]
            │
            ▼
5. [원본 봉인 및 증적 보존]
    ├─ 원본 디스크 정전기 방지 백 밀봉 및 일련번호 봉인 스티커 부착 ➔ 금고 보관
    └─ [해시 검증 결과서 및 연계보관부(CoC) 작성 ➔ 사본 이미지만 랩실 인계]
```

**동작 원리**

1. **물리적 원본 오염 차단**: 쓰기 방지 컨트롤러가 OS의 모든 쓰기 I/O 요청을 무응답 또는 거부 처리
2. **삭제된 데이터 보존**: 파일시스템 할당 테이블에서 해제된 비할당 섹터까지 그대로 덤프하여 카빙 가능 상태 유지
3. **수학적 무결성 보증**: SHA-256 해시 충돌 가능성을 배제($2^{-256}$)하여 법정에 객관적 증거능력 제시
4. **오류 섹터의 객관화**: 읽기 실패한 배드섹터 구간을 조작으로 오인하지 않도록 상세 로그 첨부
5. **SSD TRIM 특성 분석**: SSD의 경우 가비지 컬렉션(TRIM) 활성화 여부를 기록하여 비할당 영역이 0으로 초기화된 원인을 법률적으로 소명

#### 한줄 요약
- 원본 식별/쓰기 방지 결착, 사전 해시 산출, 비트스트림 이미징, 사후 해시 대조, 원본 봉인 및 CoC 작성 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **논리적 획득 vs 물리적 비트스트림 이미징 비교**:
  - 논리적 획득 (Logical Acquisition): 현재 파일시스템에 존재하는 유효 파일만 복사.
  - 물리적 이미징 (Physical Imaging): 저장매체의 모든 물리적 섹터를 통째로 복제 (삭제 데이터 포함).

</details>

| 비교 항목 | 논리적 획득 (Logical Acquisition) | 물리적 비트스트림 이미징 (Physical Imaging) |
|:---|:---|:---|
| **복제 대상 범위** | **정상 할당된 파일 및 디렉터리 구조** | **부트섹터, 할당/비할당 영역, 파일 슬랙 전체**|
| **삭제 데이터 복구**| **불가 (삭제된 파일 미포함)** | **가능 (비할당 영역 카빙을 통한 복원)** |
| **소요 시간/용량** | **빠름 (실제 파일 용량만큼만 복제)** | 드라이브 전체 용량만큼 소요 (수 시간 이상) |
| **해시 검증 대상** | 개별 파일 단위 해시 산출 | **물리 드라이브 전체 비트열 단일 해시 산출** |
| **주요 활용 목적** | 영장 범위 특정 수사, 단순 문서 확인 | **전면적 포렌식 수사, 침해 사고 원인 규명** |

#### 한줄 요약
- 논리적 획득은 정상 파일만 수집, 물리적 이미징은 비할당 영역을 포함한 전체 물리 섹터 복제이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **FIPS PUB 180-4 (보안 해시 표준) 및 NIST CFTT (도구 검증)**: 포렌식 이미징 소프트웨어 및 하드웨어 쓰기 방지기가 원본 매체를 변경하지 않음을 검증하는 미국 연방 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 수사관이 하드웨어 쓰기 방지기를 연결하지 않고 윈도우 OS에 원본 디스크를 연결하여 **파일 시스템 접근 일시(MAC Time)가 갱신되어 법정 증거 기각** | **ISO/IEC 27037 준수, NIST CFTT 인증을 통과한 하드웨어 Write Blocker를 필수 경유하여 읽기 전용(Read-only) 연결 강제** | 원본 디스크의 오염 위험 0% 차단 및 증거능력 100% 보존 |
| 구형 취약 해시 알고리즘(MD5)만을 사용하여 해시값을 산출했다가 **변호인 측의 암호학적 해시 충돌(Hash Collision) 공격으로 무결성 훼손 주장 제기** | **FIPS PUB 180-4 준수, 충돌 저항성이 검증된 SHA-256 및 SHA-512 알고리즘을 이중 적용하여 원본/사본 해시 검증서 발행** | 수학적 조작 불가능성 완벽 입증 및 무결성 공방 원천 분쇄 |
| SSD 장착 단말에서 삭제된 증거를 복원하려 했으나 **백그라운드 가비지 컬렉션(TRIM) 동작으로 인해 비할당 영역 섹터가 모두 0으로 초기화** | **단말 압수 현장에서 즉시 전원을 차단하고, 수사 보고서에 SSD 컨트롤러의 TRIM 동작 특성 및 이미징 시점 메타데이터를 공식 명시** | 증거 인멸 오해 방어 및 SSD 포렌식 결과의 법적 신뢰성 확보 |

#### 한줄 요약
- 하드웨어 쓰기 방지로 오염을 막고, SHA-256 이중 해시로 무결성을 입증하며, SSD TRIM 특성을 보고서에 명시한다.

## Ⅶ. 결론

- 디지털 포렌식 수사의 법적 성패를 결정짓는 핵심 초석인 **디스크 이미징 및 해시 무결성 아키텍처**는 법과학적 증거 보존의 절대 기준이며, 실무 구현 시 **ISO/IEC 27037 및 FIPS PUB 180-4 국제 표준 준수**, **하드웨어 쓰기 방지기(Write Blocker) 기반의 1:1 비트스트림 복제**, **SHA-256 암호 해시를 통한 원본/사본 동일성 수학적 증명**, **체인 오브 커스터디(Chain of Custody)의 철저한 기록 관리**를 통합 구축하여 최고 수준의 과학적 객관성과 법정 증거능력을 완성

#### 한줄 요약
- 쓰기 방지 장치 기반 비트스트림 이미징과 SHA-256 해시 검증 및 CoC 관리를 통해 완벽한 디스크 무결성을 완성한다.
