## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **대칭키 암호화(Symmetric Key Encryption)**: 평문을 암호화할 때 사용하는 키와 암호문을 평문으로 복호화할 때 사용하는 키가 완전히 동일한 단일 비밀키(Secret Key) 기반의 암호 알고리즘 체계.
- **AEAD(Authenticated Encryption with Associated Data, RFC 5116)**: 데이터의 기밀성(Confidentiality) 보장을 위한 암호화와 동시에, 전송 중 변조 여부를 검증하는 무결성/인증 태그(Auth Tag) 및 헤더와 같은 부가 인증 데이터(AAD)를 일체형으로 연산하는 암호화 운용 모드.

</details>

- 정의/개념: 송수신자가 사전에 공유한 **단일 비밀키(Shared Secret Key)** 를 사용하여 치환(Substitution)과 순열(Permutation) 연산을 반복 수행함으로써, 대용량 데이터의 기밀성과 무결성을 하드웨어 가속 수준의 초고속으로 보호하는 **대칭키 기반 암호 아키텍처**
- 배경/필요성: 공개키(비대칭키) 암호의 높은 수학적 계산 복잡도(소인수분해/이산대수)로 인한 성능 한계를 극복하고, 테라바이트급 스토리지 데이터 및 기가비트급 네트워크 트래픽(TLS)을 실시간으로 안전하게 보호할 요구

#### 한줄 요약
- 단일 비밀키를 기반으로 블록/스트림 연산 및 AEAD 무결성 태그를 결합하여 초고속 기밀성을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **논스(Nonce, Number used Once) / 초기화 벡터(IV)**: 동일한 평문을 동일한 비밀키로 암호화하더라도 매번 서로 다른 암호문이 생성되도록 주입하는 유일무이한 일회용 난수.
- **AES-NI(AES New Instructions)**: 인텔과 AMD x86/x64 프로세서 및 ARMv8 Crypto Extension에 내장되어 AES 라운드 연산(SubBytes, ShiftRows, MixColumns, AddRoundKey)을 1클록 단위로 고속 처리하는 하드웨어 명령어 세트.

</details>

- **초고속 연산 및 하드웨어 가속 친화성**: AES-NI 및 ARMv8 암호 가속 엔진을 통해 수십 Gbps급 라인 레이트 암호화 지원
- **AEAD 기반 기밀성·무결성 일체형 보장 (AES-GCM / ChaCha20-Poly1305)**: 암호문과 함께 128비트 인증 태그(Tag)를 생성하여 전송 중 1비트의 변조도 즉각 탐지
- **논스(Nonce) 유일성 종속성**: CTR/GCM 모드에서 논스가 1회라도 재사용될 경우 키스트림 노출 및 기밀성·무결성 붕괴 위험

#### 한줄 요약
- 하드웨어 가속 초고속 연산, AEAD 기밀성·무결성 동시 보장, 논스 유일성 기반 보안성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **키 핸들(Key Handle)**: 애플리케이션 메모리에 평문 비밀키를 노출하지 않고, HSM(하드웨어 보안 모듈)이나 KMS 내부의 키를 안전하게 지칭하여 암호 연산을 요청하는 불투명 참조 토큰.

</details>

```text
[ 애플리케이션 (Plaintext + AAD 헤더 데이터) ]
                      │
                      ▼ (Key Handle 참조 호출)
┌─────────────────────────────────────────────────────────────────────────┐
│ [ AEAD 대칭 암호 엔진 (AES-GCM / ChaCha20-Poly1305) ]                   │
│  ├─ 1. 키 관리 시스템(KMS)으로부터 128/256bit 대칭키 & 96bit Nonce 할당│
│  ├─ 2. 기밀성 연산: CTR 모드 기반 블록 암호화 ➔ [ 암호문(Ciphertext) ] │
│  └─ 3. 무결성 연산: GHASH 기반 다항식 연산 ➔ [ 128bit 인증 태그(Tag) ]  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (Ciphertext + Tag 전송)
                                     ▼
                      [ 수신단 검증 및 복호화 엔진 ]
                       ├─ 1. 수신된 Tag와 AAD를 GHASH로 재계산하여 무결성 사전 검증
                       ├─ [불일치 시] ➔ 복호화 거부 및 즉시 폐기 (MAC Error)
                       └─ [일치 시] ➔ CTR 모드로 평문 완전 복원
```

선의 의미: KMS에서 할당된 키와 논스를 바탕으로 AEAD 모듈이 암호문과 인증 태그를 동시 생성하고, 수신단이 태그를 우선 검증한 후 복호화하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **비밀키 (Secret Key)** | 암/복호화에 공통 사용되는 128/256비트 대칭키 (유출 시 전면 침해) | NIST SP 800-131A |
| **논스 / IV (Nonce)** | 암호문 무작위성을 부여하는 96비트 일회용 난수 (재사용 절대 금지) | RFC 5116 |
| **AEAD 암호 엔진** | 블록/스트림 암호화와 Galois 필드 기반 GHASH 인증 연산 동시 실행 | AES-GCM / ChaCha20 |
| **인증 태그 (Auth Tag)**| 암호문 및 AAD 데이터의 위변조 여부를 보증하는 128비트 메시지 인증 코드 | GMAC Tag |
| **KMS / HSM 금고** | 대칭키의 생성, 보관, 순환(Rotation), 파기를 안전하게 전담하는 하드웨어 | FIPS 140-3 Level 3 |

#### 한줄 요약
- 비밀키, 논스(IV), AEAD 엔진, 인증 태그, KMS/HSM 키 관리기가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인증 후 복호화(Verify-then-Decrypt)**: 수신단에서 암호문을 평문으로 풀기 전에 반드시 인증 태그의 유효성을 먼저 검증하여, 변조된 악성 페이로드 처리에 따른 CPU 자원 고갈 및 패딩 오라클 공격을 원천 차단하는 원칙.

</details>

```text
1. 송신 애플리케이션이 KMS에 평문 암호화를 요청하고 256비트 AES 키 핸들 및 고유 Nonce 획득
            │
            ▼
2. AES-GCM 엔진이 CTR 모드로 평문을 암호화하고, GHASH 연산으로 128비트 인증 태그 동시 생성
            │
            ▼
3. 네트워크를 통해 수신단으로 [Nonce + AAD + Ciphertext + Tag] 패키지 전송
            │
            ▼
4. 수신단 AEAD 엔진이 Nonce와 AAD를 바탕으로 GHASH 인증 태그를 재계산하여 수신 Tag와 대조
            │
            ├─ [Tag 불일치 / 변조 감지] ➔ 복호화 즉시 중단 및 에러 반환 (패킷 폐기)
            ▼
5. [Tag 일치 / 무결성 검증 완료] ➔ CTR 복호화 연산을 안전하게 실행하여 원본 평문 복원 완수
```

**동작 원리**

1. **키 및 논스 발급**: 세션별 유일한 96비트 카운터/난수를 생성하여 논스 중복 방지
2. **카운터 블록 생성**: $J_0 = \text{Nonce} \parallel 0^{31}1$ 초기 벡터를 설정하고 순차 증가
3. **병렬 암호화**: 각 카운터 블록을 AES 암호화하여 키스트림을 생성하고 평문과 XOR 연산
4. **인증 태그 합성**: 암호문 블록들과 AAD 길이를 Galois Field($GF(2^{128})$) 상에서 다항식 곱셈
5. **선 검증 후 복호**: 수신단에서 인증 태그 일치를 확인한 경우에만 평문 메모리 언마스킹

#### 한줄 요약
- 키/논스 할당, CTR 암호화 및 GMAC 태그 생성, 패킷 전송, 태그 사전 검증, 안전한 평문 복원 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **주요 대칭 암호화 모드 비교**: 범용 서버 표준 AES-GCM, 모바일/임베디드 특화 ChaCha20-Poly1305, 스토리지 섹터 암호화 전용 AES-XTS의 비교.

</details>

| 비교 항목 | AES-GCM (블록 기반 AEAD) | ChaCha20-Poly1305 (스트림 AEAD) | AES-XTS (섹터 단위 스토리지) |
|:---|:---|:---|:---|
| **암호화 분류** | **128비트 블록 암호 (Rijndael 기반)** | **256비트 스트림 암호 (ARX 연산)** | **블록 암호 (XEX 기반 트위크 모드)** |
| **무결성 인증 (AEAD)**| **지원 (128bit GMAC 태그 생성)** | **지원 (128bit Poly1305 태그 생성)** | **미지원 (기밀성 전용, 태그 오버헤드 없음)** |
| **하드웨어 가속** | **AES-NI 명령어 필수 (서버 최적화)** | **소프트웨어 순수 연산 최적화 (모바일)** | AES-NI 하드웨어 가속 지원 |
| **주요 장점** | x86 서버 환경에서 압도적 속도 | CPU 가속기 없는 환경에서 3배 빠름 | 섹터 크기 불변 (BitLocker 표준) |
| **주요 적용 영역** | **TLS 1.3, IPsec, 클라우드 DB 암호화**| **모바일 TLS 1.3, WireGuard VPN** | **NVMe SSD, 하드디스크 전영역 암호화**|

#### 한줄 요약
- AES-GCM은 서버/TLS 1.3 표준, ChaCha20은 모바일/WireGuard 표준, AES-XTS는 스토리지 전용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **GCM 논스 재사용 취약점(Nonce Reuse Catastrophe)**: 동일한 키로 동일한 Nonce를 2회 이상 사용하여 메시지를 암호화할 경우, 공격자가 두 암호문의 XOR 차분을 통해 GHASH 인증 키($H$)를 복구하여 임의의 위조 메시지를 생성할 수 있는 치명적 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동일 대칭키 환경에서 Nonce 재사용으로 인한 **인증 키($H$) 노출 및 암호문 위조 사고** | **결정론적 64비트 단조 증가 카운터 기반 Nonce 생성 또는 XChaCha20(192bit Nonce)** 채택 | Nonce 충돌 확률 0% 보장 및 키스트림 노출 원천 차단 |
| 수신단에서 무결성 검증 전 복호화 시도로 인한 **패딩 오라클(Padding Oracle) 및 DoS 공격** | **반드시 AEAD 태그 검증 통과 후에만 복호화를 허용하는 Verify-then-Decrypt 원칙** 강제 | 위조된 악성 페이로드 연산 거부 및 타이밍 사이드채널 공격 방어 |
| 소스 코드나 환경 변수 파일(`config.env`)에 **대칭 마스터키 하드코딩으로 인한 키 유출** | **KMS/Vault 연동 기반 키 엔벨로프(Envelope Encryption: DEK/KEK) 구조** 적용 | 소스 유출 시에도 마스터키 보호 및 자동 키 순환(Rotation) 보장 |

#### 한줄 요약
- 단조 증가 카운터로 논스 충돌을 막고, Verify-then-Decrypt로 변조를 차단하며, KMS 엔벨로프로 키를 보호한다.

## Ⅶ. 결론

- 초연결 디지털 인프라에서 대규모 데이터의 기밀성과 무결성을 보장하기 위해 **대칭키 암호화 아키텍처**는 보안 통신의 가장 핵심적인 기반 기술이며, 실무 구축 시 **AES-GCM 및 ChaCha20-Poly1305 등 표준 AEAD 모드 필수 적용**, **엄격한 Nonce 유일성 통제**, **KMS/HSM 기반 엔벨로프 암호화(Envelope Encryption) 수명주기 관리**를 통합 구현하여 완결성 높은 고신뢰 데이터 보호 환경을 완성

#### 한줄 요약
- AEAD 모드와 엄격한 논스 관리 및 KMS 기반 수명주기 통제를 결합하여 고성능 대칭키 보안을 실현한다.
