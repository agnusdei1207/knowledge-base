## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **Brewer-Nash 모델**: 과거 접근 이력에 따라 경쟁 고객 데이터 접근을 동적으로 제한하는 기밀성 모델이다.

</details>

- 정의/개념: 과거 접근 이력에 따라 경쟁 회사 데이터 접근을 제한하는 **Brewer-Nash 모델**이다.
- 배경/필요성: 고정 역할만으로는 이전 고객 접근에 따른 이해충돌을 판정할 수 없다.

#### 한줄 요약

- 같은 COI의 **기존 선택 회사만 접근 허용**

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **만리장성 정책**: 한 경쟁사 정보를 본 주체와 다른 경쟁사 사이에 논리적 장벽을 세우는 정책이다.
- **COI(Conflict of Interest)**: 교차 접근을 제한해야 하는 경쟁 회사 집합이다.

</details>

- 최초 접근 이력에 따라 **만리장성 정책**의 장벽이 형성된다.
- **COI**별로 독립적인 회사 선택이 가능하다.
- 읽기•쓰기 규칙으로 양방향 정보 흐름을 통제한다.

#### 한줄 요약

- 접근 이력 기반 **COI 동적 격리**

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **COI 클래스**: 서로 경쟁하는 회사들의 집합이다.
- **CD(Company Dataset)**: 한 회사에 속해 함께 통제할 정보 객체 집합이다.
- **정제 정보**: 특정 회사 기밀•재식별 단서를 제거해 공유 가능하다고 검증한 정보이다.

</details>

```text
Brewer-Nash 정책 구조
├─ 이해충돌 클래스 COI
├─ 회사 데이터셋 CD
├─ 주체 접근 이력
├─ 단순 보안 읽기 규칙
└─ 별표 속성 쓰기 규칙
```

| 구성요소 | 책임 |
|:---|:---|
| 이해충돌 클래스 COI | **COI 클래스**로 경쟁 회사 묶음 |
| 회사 데이터셋 CD | **CD**로 한 회사의 정보 경계 설정 |
| 주체 접근 이력 | 접근 회사•**정제 정보** 기록 |
| 단순 보안 읽기 규칙 | 동일 회사•비충돌 객체 허용 |
| 별표 속성 쓰기 규칙 | 경쟁 회사로 정보 이동 제한 |

#### 한줄 요약

- 읽기 권한과 다른 객체로의 정보 쓰기 권한을 동시에 동적 제어하여 정보 유출을 차단한다.

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **원자적 처리**: 접근 결정과 이력 기록을 끼어들기 없이 하나의 작업으로 완료하는 처리이다.
- **객체•이력 분류**: CD와 COI를 객체•이력에 연결한 판단 정보이다.
- **COI별 회사 접근 이력 조회**: 주체가 경쟁 집단별로 이미 선택한 회사를 확인하는 단계이다.
- **CD•COI•정제 여부 조회**: 요청 객체의 회사•경쟁 관계•공유 예외를 확인하는 단계이다.
- **이해충돌 장벽 접근 판정**: 접근 이력과 객체 분류를 대조해 허용 여부를 정하는 단계이다.
- **접근 결정•이력 원자적 기록**: 허용 결정과 새 접근 이력을 하나의 작업으로 저장하는 단계이다.

</details>

```text
주체•객체•행위 요청
   │
   ▼
1. COI별 회사 접근 이력 조회
   │
   ▼
2. CD·COI·정제 여부 조회
   │
   ▼
3. 이해충돌 장벽 접근 판정
   ├─ 기존 회사•비충돌•정제 ──► 접근 허용
   └─ 같은 COI의 경쟁 회사 ───► 접근 거부
                    │
                    ▼
4. 접근 결정·이력 원자적 기록
   │
   ▼
접근 결과
```

### 동작 원리

1. **COI별 회사 접근 이력 조회**: 기존 선택 회사 확인
2. **CD·COI·정제 여부 조회**: 객체·이력 분류 확인
3. **이해충돌 장벽 접근 판정**: 허용 여부 결정
4. **접근 결정·이력 원자적 기록**: 경합 우회 차단

#### 한줄 요약

- 결정·이력의 **원자적 기록**으로 경합 우회 차단

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **BLP(Bell-LaPadula Model)**: 보안 등급의 정보 흐름을 제한하는 모델이다.
- **RBAC(Role-Based Access Control)**: 역할에 권한을 묶어 배정하는 모델이다.

</details>

| 기밀성 접근 모델 | Brewer-Nash | BLP | RBAC |
|:---|:---|:---|:---|
| 적용 기준 | 경쟁 고객 이해충돌 | 군사•기밀 등급 흐름 | 직무별 권한 관리 |
| 핵심 특징 | **Brewer-Nash 모델**의 이력 기반 권한 | **BLP**의 보안 등급 흐름 | **RBAC**의 역할별 권한 |
| 한계 | 경합•정제 정보 우회 | 협업•등급 정책 제약 | 역할 폭증•과도 권한 |

> 요약: 이력, 등급, 역할 중 정책 결정 축이 다르다.

#### 한줄 요약

- Brewer-Nash는 지금 역할보다 과거에 본 고객 정보가 다음 접근을 바꾼다는 점이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **SP(Special Publication)**: NIST가 발행하는 특별간행물이다.
- **AC(Access Control)**: 접근통제 통제군이다.
- **NIST SP 800-53 AC-4**: 승인된 정보 흐름을 집행하는 통제이다.
- **IEEE(Institute of Electrical and Electronics Engineers)**: 전기전자 기술 논문•표준 기관이다.
- **Brewer•Nash 1989**: 만리장성 정책을 제시한 IEEE 원 논문이다.
- **충돌 회사 분류**: COI와 CD를 연결해 충돌 회사를 판정하는 기준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정보흐름 규칙이 분산되면 통제 우회 | **NIST**의 **SP**, **AC**, **NIST SP 800-53 AC-4** 연계 | 흐름 정책 명확화 |
| COI•CD 분류가 없으면 충돌 회사를 판정할 수 없음 | **IEEE**의 **Brewer•Nash 1989** 적용 | **충돌 회사 분류** 정립 |
| 동시 결정과 정제 정보로 장벽을 우회할 수 있음 | 원자 갱신•재식별 검증 | 경합•예외 유출 방지 |

#### 한줄 요약

- 컨설턴트가 한 은행 자료를 보면 같은 COI의 경쟁 은행 접근을 차단하고 이력을 원자적으로 남긴다.

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **이력 기반 동적 권한**: 현재 역할이 아니라 과거에 접근한 고객 정보에 따라 다음 접근을 제한하는 방식이다.
- **COI 선택**: 같은 경쟁 집단에서 기존 선택 회사만 허용하는 규칙이다.

</details>

- **이력 기반 동적 권한**과 **COI 선택**으로 기존 선택 회사만 허용하고 정제 정보는 재식별을 검증한다.

#### 한줄 요약

- 현재 역할보다 과거 고객 정보가 다음 고객 업무와 충돌하는지 판단하는 것이 핵심이다.
