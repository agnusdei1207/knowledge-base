## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모의 침투 테스트(Penetration Testing, 펜테스트)**: 조직의 정보 시스템, 네트워크, 애플리케이션에 대해 사전 승인된 법적 합의 하에 전문 보안 평가자(화이트햇 해커)가 실제 사이버 공격자의 전술·기술·절차(TTP)를 모사하여 취약점을 능동적으로 익스플로잇(Exploit)함으로써, 다계층 방어망의 실질적 침해 가능성과 비즈니스 파급력을 실증 평가하는 보안 진단 방법론.
- **교전 규칙(Rules of Engagement, RoE)**: 펜테스트 수행 전 의뢰 기관과 진단 팀 간에 법적 책임, 진단 대상 IP/URL 범위, 제외 대상(운영 DB 등), 허용 공격 기법, 테스트 시간대, 비상 중단 핫라인을 명시한 공식 구속력 있는 합의 문서.

</details>

- 정의/개념: NIST SP 800-115 및 PTES(Penetration Testing Execution Standard) 표준에 따라 **사전 기획(RoE) $\rightarrow$ 정찰(Recon) $\rightarrow$ 위협 모델링 $\rightarrow$ 취약점 분석 $\rightarrow$ 익스플로잇(침투) $\rightarrow$ 포스트 익스플로잇(권한상승/횡적이동) $\rightarrow$ 잔존물 제거(Cleanup) $\rightarrow$ 재시험(Re-testing)** 으로 이어지는 **공격 실증형 보안 평가 프로세스**
- 배경/필요성: 자동화 취약점 스캐너의 정적 점수(CVSS)만으로는 다중 취약점 결합(Vulnerability Chaining)을 통한 실제 내부망 장악 경로와 비즈니스 피해 규모를 입증할 수 없는 한계를 극복할 요구

#### 한줄 요약
- 사전 승인된 교전 규칙(RoE) 하에 공격자 기법을 실증 모사하여 다계층 방어막의 실질적 침투 경로와 통제 결함을 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최소 영향 원칙(Minimal Impact Principle)**: 상용 서비스의 가용성(Availability) 훼손을 방지하기 위해, 특정 취약점을 통한 시스템 권한 획득 가능성이 기술적으로 증명(Proof-of-Concept)된 즉시 파괴적 행위(데이터 삭제, DoS 등)를 중단하고 증적을 캡처하는 펜테스트 핵심 준칙.
- **잔존물 완전 소거(Post-Engagement Cleanup)**: 침투 과정에서 진단 목적으로 업로드한 웹쉘, 백도어 파일, 임시 생성한 관리자 계정, 수정된 방화벽 ACL을 진단 종료 즉시 완벽히 삭제하고 원상 복구하는 절차.

</details>

- **합법적 권한 및 책임 한계 정의 (RoE)**: 형법상 정보통신망법 위반을 방지하기 위한 서면 승인 및 비상 연락망(Escalation) 가동
- **취약점 연쇄 공격 실증 (Vulnerability Chaining)**: 단편적 저위험 취약점들을 결합하여 최종 권한 장악에 이르는 공격 경로 입증
- **폐쇄 루프 재검증 (Re-testing Verification)**: 발견된 결함에 대한 패치 조치 후 동일 공격 벡터로 재시험을 수행하여 차단 완결성 확정

#### 한줄 요약
- RoE 기반 법적 합의, 취약점 연쇄 실증, 최소 영향 원칙, 잔존물 소거, 재시험 완결성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PTES 7단계 실행 표준(Penetration Testing Execution Standard)**:
  1. 사전 교전(Pre-engagement) 2. 정보 수집(Intelligence Gathering) 3. 위협 모델링(Threat Modeling) 4. 취약점 분석(Vulnerability Analysis) 5. 익스플로잇(Exploitation) 6. 포스트 익스플로잇(Post Exploitation) 7. 보고(Reporting).

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 사전 기획 및 교전 규칙 수립 (Pre-Engagement & RoE) ]               │
│  ├─ 진단 범위(Scope) 확정: 특정 웹 서버 및 외부 공개 API 서브넷        │
│  └─ 비상 연락 체계(Hotline) 및 업무 영향 최소화 시간대(야간/휴일) 협의  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 정찰 및 위협 모델링 (Reconnaissance & Threat Modeling) ]          │
│  ├─ OSINT 자산 검색, 포트 스캔, 서브도메인 열거, 웹 기술 스택 식별     │
│  └─ [ 공격 시나리오 수립: 외부 SQLi ➔ 웹쉘 ➔ 내부 DB 권한 탈취 ]        │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 익스플로잇 및 영향 실증 (Exploitation & Minimal Impact) ]          │
│  ├─ 취약점 공격 코드 실행 (SQL Injection / Deserialization Exploit)     │
│  ├─ PoC 수준 권한 상승 (whoami / id 명령어 실행 결과 화면 캡처)         │
│  └─ [ 가용성 훼손 중단: DoS 및 대량 데이터 삭제 엄격 금지 ]             │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 잔존물 소거 및 최종 보고 (Post-Engagement Cleanup & Reporting) ]    │
│  ├─ 테스트용 웹쉘 및 임시 관리자 계정 완전 삭제 (Hash 무결성 검증)     │
│  └─ 경영진 요약 및 엔지니어용 세부 기술 권고 보고서 제출                │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 5. 조치 이행 및 재시험 (Remediation & Re-testing) ]                   │
│  └─ 개발/인프라팀 패치 완료 후 동일 시나리오 재실행 ➔ [취약점 차단 확정]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: RoE 합의에서 출발하여 정찰 $\rightarrow$ 익스플로잇 $\rightarrow$ 잔존물 소거 $\rightarrow$ 재시험으로 이어지는 펜테스트 표준 생애주기 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **교전 규칙 (RoE)** | 법적 승인 범위, 진단 제외 자산, 침투 허용 수준 및 비상 중단 절차 명문화 | Agreement |
| **정찰 및 위협 모델링** | OSINT 및 네트워크 스캔을 통해 표적의 공격 표면을 식별하고 진입 벡터 수립 | Recon / Threat Model|
| **익스플로잇 엔진** | 발견된 취약점을 트리거하여 타깃 시스템 쉘 획득 및 접근 권한 상승 실증 | Exploitation |
| **최소 영향 통제기** | 시스템 과부하 및 데이터 손상을 방지하기 위해 PoC 증적 획득 후 즉시 공격 중지 | Safety Control |
| **클린업 및 재시험 모듈**| 진단 아티팩트(웹쉘, 임시 계정)를 100% 소거하고 조치 후 동일 공격 재실행 검증 | Cleanup / Re-test |

#### 한줄 요약
- 교전 규칙(RoE), 위협 모델링, 익스플로잇 엔진, 최소 영향 통제기, 클린업 및 재시험 모듈이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NIST SP 800-115 침투 시험 4대 기본 단계**:
  1. **계획(Planning)**: 자원 및 목표 설정
  2. **발견(Discovery)**: 정보 수집 및 취약점 분석
  3. **공격(Attack)**: 익스플로잇 및 통제 우회 실증
  4. **보고(Reporting)**: 결과 분석 및 개선 방안 제시

</details>

```text
1. [RoE 합의] 진단 대상 IP 대역(198.51.100.0/24), 진단 시간대(22:00~06:00), 비상 핫라인 사전 정의
            │
            ▼
2. [정보 수집 및 스캔] Nmap/Burp Suite를 사용하여 외부 노출 포트, 웹 프레임워크 취약점 식별
            │
            ▼
3. [익스플로잇 및 PoC 증적 확보]
    ├─ 인증 우회 취약점을 악용하여 관리자 콘솔 접근 권한 획득
    └─ 최소 영향 원칙에 따라 화면 캡처 및 로그 기록 확보 후 즉시 프로세스 종료
            │
            ▼
4. [잔존물 제거 (Cleanup)] 테스트에 사용된 악성 페이로드 및 임시 생성 파일을 파일 시스템에서 완전 삭제
            │
            ▼
5. [보고서 제출 및 패치] 식별된 공격 체인 상세 분석 보고서 제출 ➔ 개발팀 취약점 시큐어 코딩 적용
            │
            ▼
6. [재시험 (Re-testing)] 패치 완료 후 동일 공격 페이로드 재전송 ➔ [공격 차단 완결성 검증 후 공식 종결]
```

**동작 원리**

1. **사전 경계 설정**: 운영 인프라 장애를 예방하기 위한 비즈니스 안전망 구축
2. **다각도 취약점 결합**: 단일 포트가 아닌 웹 로직과 시스템 권한 결함을 연계 공격
3. **가용성 보호 집행**: 데이터베이스 드롭(`DROP`)이나 서비스 거부 공격 일체 금지
4. **아티팩트 무결성 복원**: 진단 후 시스템을 초기 보안 상태로 100% 원복
5. **폐쇄 루프 검증**: 패치 결과를 서류가 아닌 실제 공격 재실행으로 실증 확정

#### 한줄 요약
- RoE 합의, 정보 수집, 익스플로잇 PoC, 잔존물 제거, 보고서 제출, 재시험 완결 검증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **펜테스트 3대 정보 제공 모델 비교**: 블랙박스(Zero-Knowledge), 그레이박스(Partial-Knowledge), 화이트박스(Full-Knowledge)의 비교.

</details>

| 비교 항목 | 블랙박스 (Black-box Testing) | 그레이박스 (Gray-box Testing) | 화이트박스 (White-box Testing) |
|:---|:---|:---|:---|
| **사전 제공 정보** | **IP 주소 / 도메인 외 일체 없음 (0%)** | **일반 사용자 계정 및 기본 망 구성도 (50%)**| **전체 소스코드, 시스템 설계도, 관리자 권한 (100%)**|
| **시뮬레이션 관점** | **외부 순수 공격자 (External Hacker)** | **자격증명 도용자 또는 악의적 내부자** | **보안 감사관, 아키텍트 전수 검사** |
| **진단 소요 시간** | 매우 김 (정찰 및 취약점 탐색 시간 큼) | 중간 (내부 권한 상승에 시간 집중) | 짧음~중간 (코드 분석 기반 타깃 공격) |
| **장점 및 특징** | **외부 침투 현실성 및 방어 통제력 완벽 실증**| **비용 대비 효율적 내부 횡적이동 취약점 식별**| **시스템 전반의 숨겨진 로직 결함 전수 식별** |
| **한계 및 문제점** | 내부망 심층 취약점 도달 전 시간 초과 가능 | 외부 침투 관점과 전수 검사 사이의 타협 | 실제 외부 공격자 관점의 침투 난이도 측정 곤란 |

#### 한줄 요약
- 블랙박스는 외부 실전 침투력 검증, 그레이박스는 내부 횡적이동 검증, 화이트박스는 코드 전수 결함 식별에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-115 (Technical Guide to Information Security Testing and Assessment)**: 정보 시스템의 기술적 보안 테스트와 침투 시험을 수행할 때 요구되는 방법론, 검증 절차, 보고서 양식을 규정한 미국 정부 표준 가이드라인.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모의 침투 중 고부하 익스플로잇 실행으로 인한 **운영 서비스 다운타임 및 비즈니스 중단 장애** | **교전 규칙(RoE) 내 진단 시간대(심야) 한정, 최소 영향 원칙(Minimal Impact) 및 핫라인** 운영 | 상용 서비스 가용성 영향 0% 달성 및 시스템 과부하 시 10초 내 즉시 중단 |
| 테스트 과정에서 생성된 웹쉘/백도어가 방치되어 **실제 외부 공격자의 2차 침투 경로로 악용되는 사고** | **모의 침투 종료 즉시 파일 해시 기반 잔존물 완전 소거(Cleanup) 및 체크리스트 교차 검증** | 진단 도구 방치로 인한 2차 보안 사고 원천 차단 및 시스템 상태 100% 원복 |
| 개발팀의 구두 패치 보고만 신뢰하고 종결하여 **동일 취약점을 통한 침해 위험이 잔존하는 문제** | **취약점 조치 완료 후 동일 공격 시나리오를 재실행하는 폐쇄 루프 재시험(Re-testing)** 강제 | 서류상 가짜 조치 방지 및 실제 공격 차단 실효성 100% 검증 |

#### 한줄 요약
- RoE/최소 영향으로 가용성을 지키고, Cleanup으로 백도어를 제거하며, Re-testing으로 조치를 확정한다.

## Ⅶ. 결론

- 방어자의 가정이 아닌 공격자의 실증적 관점에서 시스템의 보안성을 검증하는 **모의 침투 테스트(Penetration Testing) 아키텍처**는 능동적 보안 태세 확립의 핵심 평가 기법이며, 실무 구현 시 **NIST SP 800-115 기반 RoE 수립**, **비즈니스 가용성을 고려한 최소 영향(Minimal Impact) 원칙 준수**, **진단 잔존물(Cleanup)의 완벽한 소거**, **패치 후 재시험(Re-testing)을 통한 폐쇄 루프 검증**을 통합 집행하여 실질적이고 견고한 엔터프라이즈 방어 인프라를 완성
