## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **물리적 복제 불가 함수(PUF / Physically Unclonable Function / ISO/IEC 20897)**: 동일한 반도체 설계 도면과 공정으로 제작되더라도 실리콘 웨이퍼 제조 과정에서 불가피하게 발생하는 나노미터 단위의 물리적 미세 구조 편차(지연 시간, 도핑 농도, 임계 전압 차이)를 암호학적 챌린지-응답 쌍(CRP: Challenge-Response Pair)으로 변환하여, 칩마다 고유하고 복제 불가능한 디지털 지문(암호키)을 런타임에 생성하는 하드웨어 보안 기술.
- **불휘발성 메모리(NVM) 평문 암호키 저장 및 침습적 추출 결함(NVM Key Extraction Defect)**: 플래시 메모리(Flash/EEPROM)나 퓨즈(eFuse)에 정적으로 암호키를 저장할 경우, 공격자가 칩 패키지를 산성 용액으로 녹여(Decapsulation) 전자현미경(SEM)이나 집속이온빔(FIB)으로 물리적 프로빙(Probing)을 수행하여 비밀키를 탈취하는 구조적 결함.

</details>

- 정의/개념: 암호키를 메모리에 영구 저장하지 않고 **챌린지(Challenge) 인가 $\rightarrow$ 실리콘 고유 편차 반응 $\rightarrow$ 원시 응답(Raw Response) 관측 $\rightarrow$ 퍼지 추출기(Fuzzy Extractor) 오류 정정 $\rightarrow$ 1회용 암호키(Key) 파생 $\rightarrow$ 연산 후 메모리 즉시 소멸** 을 집행하는 **비저장형 하드웨어 지문 아키텍처**
- 배경/필요성: 플래시 메모리나 eFuse 등 기존 불휘발성 메모리(NVM)에 암호키를 정적으로 저장하는 방식은 공격자가 칩 패키징을 화학적으로 박리(Decapsulation)한 후 전자현미경(SEM) 및 집속이온빔(FIB) 물리 프로빙을 통해 비밀키를 직접 탈취하는 침습적 공격에 무력화되는 구조적 취약점이 존재함에 따라, ISO/IEC 20897 표준에 기반하여 반도체 제조 시 발생하는 불가피한 나노미터 단위의 실리콘 미세 공정 편차를 활용하고, 퍼지 추출기(Fuzzy Extractor: Gen/Rep) 오류 정정 및 헬퍼 데이터(Helper Data) 분리를 결합하는 물리적 복제 불가 함수(PUF) 아키텍처를 도입하여 **메모리 내 암호키 영구 저장 배제(비저장형 런타임 키 생성), 물리적 칩 복제 원천 차단 및 반도체 레벨의 유일무이한 하드웨어 지문 신뢰성**을 달성할 필요

#### 한줄 요약
- PUF는 반도체 제조 미세 편차를 이용해 키를 메모리에 저장하지 않고 런타임에 복원하는 하드웨어 보안 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **PUF 2대 핵심 보안 속성 및 보정 기제**:
  - **고유성 (Uniqueness)**: 서로 다른 두 칩에 동일한 챌린지를 주었을 때 응답 간의 해밍 거리(Inter-chip Hamming Distance)가 이상적으로 50%를 만족하여 장치 간 완벽히 구별되는 특성.
  - **신뢰성/재현성 (Reliability)**: 동일한 칩에 온도, 전압, 노화 등 환경 변화가 발생해도 동일한 챌린지에 대해 항상 동일한 응답(Intra-chip HD 0%)을 재생성하는 특성.
  - **퍼지 추출기 (Fuzzy Extractor)**: 환경 노이즈로 인해 발생하는 10~15%의 비트 에러를 헬퍼 데이터(Helper Data)와 ECC 오류 정정 코드로 완벽히 복원하는 알고리즘.

</details>

- **비저장형 키 생성(Key Storage-less)**: 전원이 꺼지면 암호키가 물리적으로 존재하지 않으며, 전원이 인가되어 연산이 필요할 때만 런타임에 순간 파생 후 즉시 파기
- **물리적 복제 불가능성(Unclonability)**: 칩 제조사조차 동일한 공정으로 똑같은 지문 특성을 가진 쌍둥이 칩을 물리적으로 재현 제작 불가
- **안전한 헬퍼 데이터(Helper Data) 분리**: 오류 정정을 위한 보조 정보(Helper Data)를 공개 서버나 플래시에 저장하더라도 마스터 비밀키에 대한 정보 누출 0% 보장 (Information-theoretic Security)

#### 한줄 요약
- 고유성(50% HD), 재현성(0% HD), 비저장형 키 생성, 퍼지 추출기 기반 오류 정정을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PUF 키 생성 및 인증 4대 핵심 아키텍처 컴포넌트**:
  1. **PUF Silicon Core (물리 코어)**: SRAM 셀, 아비터(Arbiter), 링 오실레이터(RO) 기반 편차 소자.
  2. **Enrollment Phase (공장 등록 단계)**: 최초 기준 응답 생성 및 오류 정정용 헬퍼 데이터(HD) 생성.
  3. **Fuzzy Extractor (퍼지 추출기)**: 정보 조정(Information Reconciliation) 및 프라이버시 증폭(Privacy Amplification).
  4. **Key Derivation Function (KDF)**: 정제된 무결성 비트열로부터 256비트 AES/ECC 마스터키 파생.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 공장 등록 단계 (Factory Enrollment Phase) ]                        │
│  ├─ 1. 챌린지 $C$ 인가 ➔ PUF 실리콘 코어에서 최초 기준 응답 $R$ 생성    │
│  └─ [ 2. 생태계 생성(Gen): $R \rightarrow$ 비밀키 $K$ + 공개 헬퍼 데이터 $HD$ 산출 ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ ($HD$는 플래시에 저장, 비밀키 $K$는 파기)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 현장 재생성 단계 (Field Key Reconstruction Phase) ]                 │
│  ├─ 1. 동일 챌린지 $C$ 인가 ➔ 환경 잡음이 섞인 노이즈 원시 응답 $R'$ 생성 │
│  └─ [ 2. 퍼지 추출기(Rep): $R' + HD \rightarrow$ 최초 무결점 비밀키 $K$ 100% 복원 ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (복원된 마스터 암호키 $K$)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 암호 연산 및 즉각 소멸 단계 (Cryptographic Execution & Zeroization)│
│  ├─ 하드웨어 암호 가속기(AES-256)에서 메모리 내 암호화/인증 연산 수행   │
│  └─ [ 연산 완료 즉시 레지스터 내 마스터키 $K$를 제로화(Zeroization) 파기]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 공장 등록 시 헬퍼 데이터를 생성하고, 현장에서 노이즈 원시 응답과 헬퍼 데이터를 결합하여 마스터키를 복원한 뒤 연산 후 즉시 파기하는 구조

| 컴포넌트 | 핵심 역할 및 기능 | 수학적/물리적 메커니즘 | 비고 |
|:---|:---|:---|:---|
| **PUF 실리콘 코어** | 반도체 공정 편차를 전기적 신호차로 증폭하여 디지털 비트열 출력 | 트랜지스터 임계전압($V_{th}$), 배선 지연($\Delta t$) | Hardware Core |
| **챌린지/응답 (CRP)** | PUF에 입력되는 자극(Challenge)과 고유하게 출력되는 지문(Response) | 일방향성(One-way) 물리 함수 관계 | CRP Interface |
| **헬퍼 데이터 (HD)** | 노이즈로 오염된 비트를 원래 기준값으로 복원하기 위한 오류 정정 신드롬 | BCH 코드, Reed-Solomon 코드 신드롬 | Public Data |
| **퍼지 추출기 (FE)** | 헬퍼 데이터를 활용한 에러 정정(Rep) 및 해시 기반 균일 난수성(PA) 확보 | Secure Sketch + Hash Function | Cryptographic |
| **KDF 암호 파생기** | 무결 복원된 지문 비트열을 AES/ECC 표준 대칭/비대칭 키로 변환 | HKDF-SHA256, HMAC | Key Derivation|

#### 한줄 요약
- 실리콘 코어가 비휘발성 메모리에 키를 넣어 두던 자리를 공정 편차라는 물리 고유성으로 대신하고, 헬퍼 데이터는 비밀을 담지 않는 오류 정정 신드롬이라 공개 저장해도 되며, 퍼지 추출기와 KDF를 거쳐 나온 키는 연산 직후 제로화되어 칩 어디에도 남지 않는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PUF 키 라이프사이클 3단계 프로세스**:
  1. 공장 호적 등록 단계
  2. 필드 현장 키 복원 단계
  3. 보안 연산 및 즉각 파기

</details>

```text
1. [공장 호적 등록 단계 (Enrollment)]
    ├─ 공장 테스트 베드에서 MCU 전원 On ➔ SRAM PUF 초기 기동 값($R$) 읽기
    ├─ Fuzzy Extractor `Gen(R)` 실행 ➔ 암호키 $K$ 및 오류보정 헬퍼 데이터 $HD$ 생성
    └─ [$HD$를 일반 비휘발성 플래시에 기록하고, 칩 전원 Off ➔ 키 $K$는 완전 소멸]
            │
            ▼
2. [필드 현장 키 복원 단계 (Key Reconstruction)]
    ├─ 가혹 환경(고온/저전압)에서 기기 부팅 ➔ 노이즈가 포함된 SRAM 값($R'$) 획득
    ├─ 플래시에서 $HD$ 로드 ➔ Fuzzy Extractor `Rep(R', HD)` 오류 정정 알고리즘 실행
    └─ [BCH 디코딩을 통해 10% 비트 에러를 100% 교정 ➔ 공장 등록 시 $K$ 완벽 복원]
            │
            ▼
3. [보안 연산 및 즉각 파기]
    ├─ 복원된 키 $K$를 암호 가속기에 로드 ➔ TLS 세션 키 협상 및 디스크 복호화
    └─ [연산 완료 즉시 레지스터 및 RAM 버퍼를 0x00으로 제로화(Zeroize) 영구 파기]
```

**동작 원리**

1. **공장 호적 등록 단계**: 기준 응답에서 키와 헬퍼 데이터 생성
2. **필드 현장 키 복원 단계**: 노이즈 응답을 ECC로 보정해 키 복원
3. **보안 연산 및 즉각 파기**: 연산 후 휘발성 키를 제로화

#### 한줄 요약
- 저장된 키를 없앤 대가로 온도·전압에 따라 흔들리는 응답을 매번 정정해야 하므로, PUF의 실용성은 퍼지 추출기가 감당할 수 있는 오류율 범위가 결정한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PUF 3대 주요 구현 방식 비교**:
  - SRAM PUF (약한 PUF): 전원 인가 시 SRAM 셀 트랜지스터의 비대칭성 초기값 활용 (내부 키 생성 전용).
  - Arbiter PUF (강한 PUF): 대칭 지연 경로에서 신호의 도착 속도 차이 레이스 판정 (외부 기기 인증 전용).
  - Ring Oscillator (RO) PUF: 링 발진기 간의 미세한 주파수 발진 속도 차이 비교 (중간 복잡도).

</details>

| 비교 항목 | SRAM PUF (약한 PUF) | Arbiter PUF (강한 PUF) | Ring Oscillator PUF (RO PUF) |
|:---|:---|:---|:---|
| **물리적 원리** | **SRAM 셀 기동 시 0/1 비트 비대칭성** | **두 대칭 지연 경로 간 레이스(Race) 판정**| **인버터 링 회로 간 발진 주파수 차이** |
| **CRP 공간 크기** | **제한적 (1개 또는 극소수 챌린지)** | **매우 큼 ($2^N$개의 무한 챌린지-응답)**| 중간 (선택 가능한 링 쌍의 수) |
| **주요 용도** | **장치 내부 마스터 암호키 안전 파생 (KDF)**| **외부 서버와 다이렉트 상호 기기 인증** | FPGA 기반 암호키 생성 및 기기 식별 |
| **주요 공격 위협** | 노화에 따른 불안정 비트 에러 | **AI 머신러닝 기반 모델링 공격(Modeling)**| 온도/전압 변동에 따른 주파수 드리프트|
| **하드웨어 면적** | **매우 작음 (기존 시스템 SRAM 재활용)**| 작음 (멀티플렉서 및 래치 회로) | 큼 (다수의 링 인버터 및 카운터) |

#### 한줄 요약
- SRAM PUF는 내부 키 생성, Arbiter PUF는 외부 기기 인증, RO PUF는 FPGA 주파수 비교에 최적화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/IEC 20897-1/2 및 머신러닝 모델링 공격 (Modeling Attack)**: PUF 보안 요구사항 및 평가 표준, 그리고 공격자가 다량의 CRP를 수집하여 AI로 PUF 회로를 수학적으로 복제하는 공격 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 산업용 고온/저온 환경에서 노이즈가 급증하여 비트 에러율이 증가함에 따라 **퍼지 추출기 오류 복원 실패로 인한 기기 부팅 장애 발생** | **ISO/IEC 20897-2 표준 준수, BCH 코드 에러 정정 능력을 15% 이상 설계하고 다중 샘플링 다수결 투표(Majority Voting) 적용** | 가혹 환경에서도 100% 신뢰성 있는 암호키 재현 달성 |
| 공격자가 강한 PUF(Arbiter)에 수십만 건의 챌린지를 전송하고 응답을 수집하여 **AI 머신러닝으로 칩 지문을 수학적으로 복제 예측 (Modeling Attack)** | **챌린지 입력단에 암호학적 해시(SHA-256)를 배치하여 비선형성을 강화하고, 질의 속도 제한(Rate Limiting) 프로토콜 적용** | AI 딥러닝 모델링 복제 공격 100% 원천 차단 |
| 제조 공정에서 칩 간 고유성이 떨어지는 편향된(Biased) PUF 셀이 포함되어 **서로 다른 두 기기가 동일한 암호키를 생성하는 충돌 사고 발생** | **ISO/IEC 20897-1 기반 칩 출하 전 전수 테스트를 수행하여 칩 간 해밍 거리(Inter-chip HD) 50% $\pm$ 2% 합격 칩만 선별** | 기기 간 키 충돌 0% 및 글로벌 암호학적 엔트로피 보증 |

#### 한줄 요약
- BCH 다수결 투표로 환경 에러를 극복하고, 입력단 해시로 AI 모델링을 차단하며, ISO 20897로 50% 고유성을 보증한다.

## Ⅶ. 결론

- 암호키를 메모리에 저장하지 않고 칩 고유의 물리적 편차로부터 런타임에만 파생하여 물리적 해킹을 무력화하는 **차세대 하드웨어 신뢰 앵커 및 칩 지문 보안(ISO/IEC 20897 / PUF / Fuzzy Extractor)의 최상위 원천 기술**로 확고히 자리 잡았으며, IoT 기기 신원 인증, 스마트카드 및 양자 내성 암호(PQC) 하드웨어 루트키로 진화하는 가운데, 실무 반도체 PUF 설계 및 적용 시에는 **내부 마스터키 생성을 위한 SRAM PUF(약한 PUF)와 외부 인증용 Arbiter PUF(강한 PUF)의 목적별 최적 분기, 15% 이상 에러 정정 능력을 갖춘 BCH/다수결 투표 퍼지 추출기 설계, 머신러닝 모델링 공격 방어를 위한 챌린지 입력단 비선형 해시(SHA-256) 결합**을 결합하여 완벽한 하드웨어 PUF 신뢰성을 완성

#### 한줄 요약
- ISO/IEC 20897 표준과 퍼지 추출기 오류 정정 및 비저장형 키 수명관리를 통해 완벽한 PUF 하드웨어 보안을 완성한다.
