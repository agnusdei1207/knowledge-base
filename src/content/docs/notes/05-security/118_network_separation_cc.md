## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **망분리**: 업무망•인터넷망 등 보안영역을 격리하고 연계 경로를 통제하는 구조이다.

</details>

- 정의/개념: **망분리**로 보안영역을 격리하고 공통평가기준으로 보안제품 기능과 보증수준을 검증한다.
- 배경/필요성: 평면망•무검사 연계로는 외부 침해의 업무망 진입과 횡적 이동을 제한할 수 없다.

#### 한줄 요약

- 망을 나눠도 통로와 제품 설정이 약하면 공격이 가능하다는 점이 핵심이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최소 연계**: 분리된 영역 사이에 필요한 경로만 허용하고 데이터 흐름을 검사하는 원칙이다.
- **공통평가기준(Common Criteria, CC)**: 정보보호제품의 보안기능과 보증수준을 평가•인증하는 기준이다.
- **보안적합성 검증**: 공공기관에 도입하는 정보보호제품의 안전성과 실제 구성 적합성을 확인하는 절차이다.

</details>

- **최소 연계**로 공격 이동과 피해 범위를 제한한다.
- 망연계•관리 경로를 집중 통제하고 감사한다.
- **CC** 평가와 **보안적합성 검증**의 목적을 구분한다.

#### 한줄 요약

- 인증 제품도 평가 범위 밖 기능이나 잘못된 설치 설정까지 자동으로 안전해지지는 않음이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **평가대상(Target of Evaluation, TOE)**: CC에서 보안성 평가 범위로 정의한 대상이다.
- **보호프로파일(Protection Profile, PP)**: 제품군의 공통 보안문제•목표•요구사항을 정의한 문서이다.

</details>

```text
망분리 보안구조
├─ 업무 · 인터넷 · 관리 영역
│  └─ 보안등급 · 업무별 경계
├─ 망연계 · 자료전송 경계
│  └─ 승인 · 검사 · 무해화 · 최소 허용
├─ CC 인증 TOE · 버전
│  └─ 인증서 · PP · 평가범위 · 형상
├─ 안전한 설치 · 관리 구성
│  └─ 계정 · 패치 · 관리 경로
└─ 로그 · 우회 · 변경 검증
   └─ 전송 · 예외 · 정책 효과
```

| 구성요소 | 책임 |
|:---|:---|
| 업무•인터넷•관리 영역 | 보안등급•업무별 경계 분리 |
| 망연계•자료전송 경계 | 승인•검사•무해화•최소 허용 |
| CC 인증 TOE•버전 | **TOE** 인증서•평가범위와 **PP**•형상 확인 |
| 안전한 설치•관리 구성 | 계정•패치•관리 경로 통제 |
| 로그•우회•변경 검증 | 전송•예외•정책 효과 점검 |

#### 한줄 요약

- 영역 사이에 필요한 통신만 허용하고 모든 예외 전송과 관리 작업을 기록하는 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **보안영역 간 흐름**: 망 경계의 승인된 연계 지점에서만 검사•통제되는 데이터 이동이다.
- **CC 평가 범위**: TOE•PP•인증 버전•형상으로 한정된 제품 보증 경계이다.
- **업무•데이터 흐름 분석**: 서비스•관리•외부 연결의 필요 흐름을 식별하는 단계이다.
- **분리 영역•최소 연계 요구 확정**: 영역 경계와 허용 정보•방향•검사 기준을 정하는 단계이다.
- **CC 범위•버전•형상 검증**: 인증서의 TOE•PP•버전•형상이 도입 대상과 같은지 확인하는 단계이다.
- **전송•관리•로그 통제 집행**: 승인•무해화•감사 정책을 실제 경로에 적용하는 단계이다.
- **우회 경로•구성 시정 결정**: 예외•패치•공유 기능의 통제 공백을 보완하는 단계이다.

</details>

```text
업무 · 데이터 흐름 요구
            │
            ▼
1. 업무•데이터 흐름 분석
            │
            ▼
2. 분리 영역•최소 연계 요구 확정
            │
            ▼
3. CC 범위•버전•형상 검증
            │
            ▼
4. 전송•관리•로그 통제 집행
            │
      우회 · 변경 · 효과 검증
            ▼
5. 우회 경로•구성 시정 결정
            │
            └─ 영역 · 연계 요구로 환류
```

### 동작 원리

1. **업무·데이터 흐름 분석**: 서비스·외부 연결 분석
2. **분리 영역·최소 연계 요구 확정**: 방향·검사 기준 결정
3. **CC 범위·버전·형상 검증**: 인증서·도입 형상 대조
4. **전송·관리·로그 통제 집행**: 승인·무해화·감사 기록
5. **우회 경로·구성 시정 결정**: 예외·공유 기능 보완

#### 한줄 요약

- 먼저 필요한 정보 흐름을 그려야 업무를 막지 않으면서 위험한 통로만 통제할 수 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **물리적 망분리**: 별도 장비•회선으로 보안영역을 격리하는 방식이다.
- **논리적 망분리**: 가상화로 실행영역을 분리하는 방식이다.
- **가상 데스크톱 인프라(Virtual Desktop Infrastructure, VDI)**: 중앙 서버에서 가상 데스크톱을 제공하는 인프라이다.

</details>

| 망분리 방식 | 물리적 망분리 | 논리적 망분리 |
|:---|:---|:---|
| 적용 기준 | 강한 격리•명확한 경계 | 유연한 전환•중앙 관리 |
| 핵심 특징 | **물리적 망분리**로 장비•회선 분리 | **논리적 망분리**와 **VDI**로 실행영역 분리 |
| 한계 | 이동식 매체•망연계 우회 | 가상화 오류•공유 기능 경계 약화 |

#### 한줄 요약

- 물리 방식은 경로가 분명하고 논리 방식은 유연하지만 둘 다 연계와 관리 통제가 필요하다는 점이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO(International Organization for Standardization)**: 국제표준화기구이다.
- **IEC(International Electrotechnical Commission)**: 국제전기기술위원회이다.
- **ISO/IEC 15408**: CC의 보안기능•보증 평가기준을 규정한 표준이다.
- **ISO/IEC 18045**: CC의 평가 방법론을 규정한 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 제품 보안성 평가 | **ISO/IEC 15408** 확인 | TOE 보증범위 파악 |
| 평가 방법론 | **ISO/IEC 18045** 적용 | 평가 일관성 확보 |
| 공공기관 도입 | **보안적합성 검증** 별도 수행 | 설치•운용 안전성 확인 |

- **ISO**와 **IEC**의 공동 표준으로 CC 평가기준과 방법론을 확인한다.

#### 한줄 요약

- 외부망 파일은 반입 목적과 사용자를 승인하고 악성코드 검사와 무해화를 통과한 자료만 내부망으로 중계하며 전 과정을 감사한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **통제 지점 중심 설계**: 분리 방식의 수보다 실제 연계 경로와 우회 가능성을 관리하는 원칙이다.

</details>

- **통제 지점 중심 설계**에 따라 강한 경계는 물리적 망분리, 유연한 전환은 논리적 망분리를 적용하고 모두 최소 연계를 검증한다.

#### 한줄 요약

- 벽의 개수보다 벽에 난 문을 누가 어떻게 사용하고 기록하는지가 실제 보안을 결정하는 것이 핵심이다.
