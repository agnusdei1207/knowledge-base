## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **동형 암호(Homomorphic Encryption, HE)**: 평문 데이터를 복호화하지 않고 암호문(Ciphertext) 상태 그대로 덧셈, 곱셈, 다항식 연산을 수행하여도, 그 연산 결과 암호문을 복호화했을 때 평문 상태에서 직접 연산한 결과와 수학적으로 정확히 일치($\text{Dec}(\text{Enc}(m_1) \oplus \text{Enc}(m_2)) = m_1 + m_2$)하도록 보증하는 4세대 공개키 암호 기술.
- **완전 동형 암호(Fully Homomorphic Encryption, FHE)**: 덧셈과 곱셈 연산 횟수의 제한 없이 임의의 복잡한 튜링 완전(Turing-Complete) 컴퓨터 프로그램을 암호문 상에서 무제한 실행할 수 있는 동형 암호 체계 (2009년 Craig Gentry 제안).

</details>

- 정의/개념: 격자 기반 암호(RLWE: Ring Learning With Errors)를 바탕으로 **평문 노출 없는 연산(Data-in-Use Protection)** 을 실현하고, 무제한 곱셈 연산을 위해 노이즈를 주기적으로 제거하는 **부트스트래핑(Bootstrapping)** 메커니즘을 내장한 **프라이버시 보존형 암호 프레임워크**
- 배경/필요성: 클라우드 컴퓨팅 및 외부 AI 서버에 민감 데이터(의료 기록, 금융 거래, 유전체 정보) 위탁 분석 시, 연산을 위해 메모리 상에 평문으로 복호화해야 함에 따라 발생하는 데이터 유출 위협을 원천 차단할 요구

#### 한줄 요약
- 암호문 상태 그대로 복호화 없이 덧셈/곱셈 연산을 수행하여 데이터 처리 중(In-Use) 기밀성을 보장한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **노이즈 예산(Noise Budget)**: 암호문 생성 시 보안성을 위해 주입된 작은 오차(Noise)가 곱셈 연산을 거칠 때마다 기하급수적으로 증폭되며, 이 노이즈가 암호문의 모듈러스 한계를 초과하면 복호화 오류가 발생하므로 잔여 허용치를 관리하는 척도.
- **부트스트래핑(Bootstrapping)**: 노이즈가 임계치에 도달한 암호문에 대해, 암호화된 복호화 회로를 동형 연산으로 스스로 실행하여 평문 노출 없이 '노이즈가 초기화된 깨끗한 새 암호문'으로 재생성하는 연산 리프레시 기술.

</details>

- **데이터 사용 중(In-Use) 기밀성 100% 보증**: 클라우드 인프라 제공자나 악의적 내부자도 연산 중인 원본 데이터를 일절 열람 불가
- **연산 복잡도 및 메모리 오버헤드**: 평문 대비 암호문 크기가 수천 배 증가하고, 부트스트래핑 연산에 수백 ms~수 초의 CPU 연산 시간 소요
- **계산 무결성(Integrity) 검증 한계**: 연산 중 기밀성은 보장되나, 클라우드 서버가 임의로 연산 수식을 조작했는지는 검증할 수 없어 영지식 증명(ZKP)과의 결합 요구

#### 한줄 요약
- 복호화 없는 연산 처리, 부트스트래핑 기반 노이즈 관리, 높은 연산 오버헤드, ZKP 결합 필요성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SIMD 패킹(Single Instruction Multiple Data / Ciphertext Slot)**: 다항식의 슬롯(Slot) 구조를 활용하여 단 1개의 암호문에 수천 개의 평문 데이터 벡터(예: 8,192개)를 병렬 패킹한 후, 단 한 번의 동형 연산으로 수천 개 데이터를 동시 일괄 계산하는 최적화 기법.
- **평가 키(Evaluation Key / Relinearization Key)**: 두 암호문의 곱셈 연산 후 2차에서 3차로 팽창된 다항식 차수를 다시 2차 다항식으로 축소(Relinearization)하기 위해 서버에 제공하는 보조 공개키.

</details>

```text
[ 데이터 소유자 (Client / Enterprise) ]
 ├─ 평문 데이터 벡터 ($m_1, m_2, \dots, m_n$)
 ├─ 키 생성기: 비밀키($sk$), 공개키($pk$), 평가 키($evk$)
 └─ SIMD 인코더 & RLWE 암호화 엔진
           │
           ▼ [ 1. 암호문 $C_1, C_2$ 및 평가 키($evk$) 전송 (비밀키 $sk$는 절대 미전송) ]
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ 신뢰할 수 없는 클라우드 서버 (Untrusted Cloud Server) ]                                       │
│  ├─ 2. 동형 평가 엔진 (Homomorphic Evaluator):                                                   │
│  │    ├─ 동형 덧셈 ($C_{\text{add}} = C_1 \oplus C_2$) ── (노이즈 증가 미미)                     │
│  │    ├─ 동형 곱셈 ($C_{\text{mul}} = C_1 \otimes C_2$) ── (노이즈 급격 증가)                    │
│  │    └─ 재선형화(Relinearization) 및 모듈러스 축소(ModSwitch)                                   │
│  └─ 3. 노이즈 포화 시: [ 부트스트래핑 엔진 (Bootstrapping Circuit) ] ➔ 노이즈 초기화             │
└──────────────────────────────────┬───────────────────────────────────────────────────────────────┘
                                   │
                                   ▼ [ 4. 연산 결과 암호문 $C_{\text{result}}$ 반환 ]
                      [ 클라이언트 복호화 ($m_{\text{result}} = \text{Dec}_{sk}(C_{\text{result}})$) ]
```

선의 의미: 클라이언트가 데이터를 암호화하여 평가 키와 함께 클라우드로 전송하면, 클라우드가 평문 복호화 없이 동형 연산을 수행한 후 결과 암호문만을 반환하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **SIMD 인코더/디코더** | 평문 실수/정수 배열을 원분 다항식(Cyclotomic Polynomial) 슬롯으로 변환 | SIMD Slot |
| **RLWE 암호화 엔진** | Ring-LWE 난제를 기반으로 평문 다항식에 노이즈를 주입하여 암호문 생성 | Lattice Crypto |
| **평가 키 (Evaluation Key)**| 곱셈 후 차수 축소(Relinearization) 및 슬롯 회전(Galois Key)을 위한 보조키 | Public Key |
| **동형 평가기 (Evaluator)** | 덧셈, 곱셈, 스칼라 연산 회로를 암호문 상에서 직접 실행하는 연산 엔진 | Crypto Engine |
| **부트스트래핑 엔진** | 노이즈가 포화된 암호문을 평문 노출 없이 초기 노이즈 수준으로 갱신 | FHE Core |

#### 한줄 요약
- SIMD 인코더, RLWE 암호화기, 평가 키, 동형 평가기, 부트스트래핑 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **동형 암호 연산 라이프사이클**:
  1. **파라미터 선정**: 목표 회로 깊이(곱셈 계층 수)에 따라 다항식 차수 $N$(예: 8192, 16384) 및 모듈러스 체인 $Q$ 결정
  2. **암호화 및 전송**: 클라이언트가 $pk$로 암호화한 $C_A, C_B$를 서버에 업로드
  3. **동형 평가**: 서버가 곱셈($C_A \times C_B$) 및 재선형화, 리스케일링(Rescaling) 연산 반복
  4. **부트스트래핑**: 노이즈 예산 소진 시 암호문 상태로 복호화 회로 실행
  5. **복호화**: 클라이언트가 자신의 $sk$로 복호화하여 $f(A, B)$의 평문 결과 획득

</details>

```text
1. 클라이언트가 목표 연산 회로(AI 모델 깊이)를 분석하여 다항식 차수($N$) 및 노이즈 파라미터 생성
            │
            ▼
2. 대용량 평문 데이터를 SIMD 슬롯에 패킹 후 RLWE 공개키($pk$)로 암호화하여 클라우드로 전송
            │
            ▼
3. 클라우드 서버가 전달받은 암호문 간 동형 덧셈/곱셈 및 RelinKey 기반 차수 축소 연산 수행
            │
            ▼
4. [노이즈 예산 소진 시] ➔ 서버가 부트스트래핑 알고리즘을 가동하여 노이즈를 0에 가깝게 리셋
            │
            ▼
5. 최종 연산 결과 암호문 수신 ➔ 클라이언트가 개인키($sk$)로 복호화하여 평문 분석 결과 획득
```

**동작 원리**

1. **파라미터 초기화**: $N=16384, \log Q=438$ 등 128비트 양자 보안 강도를 만족하는 파라미터 선택
2. **슬롯 패킹**: 복소수/정수 벡터를 정칙 다항식의 잉여류환 상으로 역이산 푸리에 변환(IDFT) 인코딩
3. **암호화 연산**: $C = (c_0, c_1) = (a \cdot s + m + e, -a)$ 형태로 암호화하여 노이즈 $e$ 주입
4. **동형 곱셈 및 노이즈 관리**: 텐서곱 연산 후 차수를 2차로 낮추고 계수를 스케일링($\Delta$)으로 나눔
5. **안전한 복구**: 수신된 $(c_0, c_1)$에 $c_0 + c_1 \cdot s = m + e$를 연산하고 반올림하여 $m$ 복원

#### 한줄 요약
- 회로 파라미터 선정, SIMD 패킹 암호화, 동형 평가 및 재선형화, 부트스트래핑, 개인키 복호화 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **주요 동형암호 스킴 비교**: 무오차 정수 연산 표준 BGV/BFV, 고속 실수 근사 연산 최적화 CKKS, 비트 단위 고속 부트스트래핑 TFHE의 비교.

</details>

| 스킴 명칭 | 주 데이터 타입 | 핵심 연산 특성 | 노이즈 관리 기법 | 주요 적용 분야 |
|:---|:---|:---|:---|:---|
| **BGV / BFV** | **정수 (Exact Integer)** | **무오차 완벽한 정수 연산 보장** | Modulus Switching / Leveled | **금융 거래 집계, 데이터베이스 일치 검색, 전자투표** |
| **CKKS** | **실수 (Approximate Real)** | **근사치 연산 (노이즈를 유효숫자 뒤 오차로 흡수)** | **Rescaling (스케일 정렬)** | **AI/머신러닝 추론, 생체/의료 데이터 분석, 유전체 통계**|
| **TFHE / FHEW** | **비트/불리언 (Bit/Boolean)** | **게이트(AND, XOR) 단위 초고속 부트스트래핑($\le 10\text{ms}$)** | **Gate Bootstrapping** | **암호화 제어 로직, 분기문 연산, 보안 임베디드 회로** |

#### 한줄 요약
- BGV/BFV는 금융/DB 정수 전용, CKKS는 AI/ML 실수 근사치 전용, TFHE는 불리언 게이트 연산 전용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CKKS 정밀도 손실(Precision Loss)**: CKKS 스킴에서 연속적인 곱셈 후 리스케일링(Rescaling)을 수행할 때 하위 비트의 정밀도가 점진적으로 유실되어, 딥러닝 추론 결과의 정확도가 크게 저하되는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 깊은 곱셈 연산 도중 노이즈 예산 초과로 인한 **복호화 실패 및 원본 데이터 영구 손실** | **연산 회로 깊이에 맞춘 Leveled 파라미터 사전 설계 및 GPU 가속 부트스트래핑** | 노이즈 오버플로우 0% 차단 및 무제한 깊이 연산 연속성 보장 |
| CKKS 기반 딥러닝 추론 시 비선형 활성화 함수(ReLU) 처리 불능 및 **정밀도 급격 저하** | **ReLU 함수를 Chebyshev 다항식으로 근사화하고 60비트 스케일 팩터 리스케일링** | AI 모델 추론 정확도 99% 이상 보존 및 부동소수점 오차 최소화 |
| 동형 연산 서버가 악의적으로 수식을 변조하거나 결과를 왜곡하는 **계산 무결성 훼손** | **동형 연산 회로와 결합된 영지식 증명(zk-SNARKs) 또는 검증 가능 연산(VC)** 적용 | 서버의 임의 수식 조작 즉각 탐지 및 연산 결과 신뢰성 100% 보증 |

#### 한줄 요약
- Leveled 설계로 노이즈를 제어하고, Chebyshev 근사로 AI 정밀도를 유지하며, ZKP로 계산 무결성을 검증한다.

## Ⅶ. 결론

- 클라우드 컴퓨팅 및 생성형 AI 시대의 궁극적인 프라이버시 보호 기술인 **동형 암호(Homomorphic Encryption) 아키텍처**는 데이터 주권(Data Sovereignty)과 규제 컴플라이언스(GDPR/개인정보보호법)를 준수하는 핵심 동력이며, 실무 구현 시 **도메인별 최적 스킴 선정(정수 BGV vs AI CKKS)**, **GPU/NPU 기반 하드웨어 가속 부트스트래핑**, **계산 무결성 보장을 위한 영지식 증명(ZKP) 결합**을 통합 추진하여 실용성 높은 고성능 프라이버시 보존 연산 환경을 완성

#### 한줄 요약
- BGV/CKKS 동형 스킴과 GPU 가속 부트스트래핑 및 ZKP 무결성 검증을 결합하여 완벽한 데이터 활용 보안을 실현한다.
