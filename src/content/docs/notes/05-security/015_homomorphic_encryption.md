## 미리 알고가기

- **동형 암호(Homomorphic Encryption)**: [읽기: 에이치오엠오엠오알피에이치아이씨; 표기 이유: 영문 머리글자와 구분 기호] 암호문을 복호화하지 않고 계산해도 복호화한 결과가 평문 계산 결과와 대응하는 공개키 암호
- **평문·암호문(Plaintext·Ciphertext)**: [읽기: 피엘에이아이엔티이엑스티씨아이피에이치이알티이엑스티; 표기 이유: 영문 머리글자와 구분 기호] 원본 데이터와 비밀키 없이는 내용을 알기 어렵게 변환한 데이터
- **동형성(Homomorphism)**: [읽기: 에이치오엠오엠오알피에이치아이에스엠; 표기 이유: 영문 머리글자와 구분 기호] 평문에서 한 연산과 암호문에서 한 연산의 결과가 복호화 뒤 서로 대응하는 성질
- **제한 동형 암호(Leveled Homomorphic Encryption)**: [읽기: 엘이브이이엘이디; 표기 이유: 영문 머리글자와 구분 기호] 미리 정한 회로 깊이 안에서 덧셈·곱셈을 수행하는 동형 암호
- **완전 동형 암호(Fully Homomorphic Encryption, FHE)**: [읽기: 에프에이치이; 표기 이유: 영문 머리글자와 구분 기호] 부트스트래핑으로 노이즈를 줄여 임의 깊이의 계산을 이어갈 수 있는 동형 암호
- **회로 깊이(Circuit Depth)**: [읽기: 씨아이알씨유아이티; 표기 이유: 영문 머리글자와 구분 기호] 앞 연산 결과에 의존해 순차적으로 이어지는 곱셈 단계 수
- **노이즈 예산(Noise Budget)**: [읽기: 엔오아이에스이; 표기 이유: 영문 머리글자와 구분 기호] 암호문 계산으로 노이즈가 증가해도 정확히 복호화할 수 있는 허용 범위
- **모듈러스(Modulus)**: [읽기: 엠오디유엘유에스; 표기 이유: 영문 머리글자와 구분 기호] 동형 암호의 계수 계산 범위를 정하고 노이즈 예산과 보안 수준에 영향을 주는 나눗셈 기준값
- **레벨(Level)**: [읽기: 엘이브이이엘; 표기 이유: 영문 머리글자와 구분 기호] 연속 계산 중 남아 있는 모듈러스 단계와 추가 곱셈 가능 범위를 나타내는 상태
- **스케일(Scale)**: [읽기: 에스씨에이엘이; 표기 이유: 영문 머리글자와 구분 기호] CKKS가 실숫값의 정밀도를 유지하기 위해 값에 곱해 정수처럼 표현하는 크기 기준
- **부트스트래핑(Bootstrapping)**: [읽기: 비오오티에스티알에이피피아이엔지; 표기 이유: 영문 머리글자와 구분 기호] 암호문 상태에서 복호화 회로를 평가해 노이즈를 줄이고 추가 연산 여유를 만드는 기법
- **재선형화(Relinearization)**: [읽기: 알이엘아이엔이에이알아이지에이티아이오엔; 표기 이유: 영문 머리글자와 구분 기호] 암호문 곱셈 뒤 커진 암호문 차수를 평가 키로 줄이는 기법
- **평가 키(Evaluation Key)**: [읽기: 이브이에이엘유에이티아이오엔; 표기 이유: 영문 머리글자와 구분 기호] 재선형화·슬롯 회전·부트스트래핑 같은 암호문 연산을 지원하는 공개 보조 키
- **암호문 슬롯(Ciphertext Slot)**: [읽기: 씨아이피에이치이알티이엑스티; 표기 이유: 영문 머리글자와 구분 기호] 한 암호문에 여러 값을 넣어 같은 연산을 병렬 적용하는 논리적 위치
- **BFV(Brakerski-Fan-Vercauteren)**: [읽기: 비에프브이; 표기 이유: 영문 머리글자와 구분 기호] 정확한 정수·모듈러 연산을 지원하는 동형 암호 방식
- **BGV(Brakerski-Gentry-Vaikuntanathan)**: [읽기: 비지브이; 표기 이유: 영문 머리글자와 구분 기호] 레벨별 모듈러스 전환으로 깊은 정수 연산을 지원하는 동형 암호 방식
- **CKKS(Cheon-Kim-Kim-Song)**: [읽기: 씨케이케이에스; 표기 이유: 영문 머리글자와 구분 기호] 스케일을 조정하며 실수·복소수의 근삿값을 계산하는 동형 암호 방식


## Ⅰ. 개요

- **정의/개념**: 암호문 계산 결과가 평문 계산과 대응
- **배경/필요성**: 외부 계산자에게 원문 없는 분석 위탁

### 쉽게 이해하기 (학습용)

- 서버가 잠긴 상자를 열지 않고도 안의 숫자를 계산해 새 상자로 돌려주면, 비밀키를 가진 소유자만 결과를 확인한다.

## Ⅱ. 특징

- 곱셈 깊이가 노이즈·복호화 성공을 좌우한다
- 암호문 크기·연산량이 평문보다 증가한다
- 기밀성은 제공하지만 계산 무결성은 보장하지 않는다

### 쉽게 이해하기 (학습용)

- 서버는 원문을 볼 수 없지만 계산을 빼먹거나 다른 회로를 실행할 수 있으므로, 암호화와 별도로 계산 결과가 맞는지 검증해야 한다.

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    subgraph O["데이터 소유자 경계"]
        E["인코더·암복호화기"]
        K["키·파라미터 저장소"]
        K -->|"공개키·비밀키·파라미터"| E
    end
    subgraph U["비신뢰 계산 경계"]
        V["동형 평가 엔진"]
        N["노이즈·레벨 관리자"]
        V <--> N
    end
    E -->|"입력 암호문·평가 키"| V
    V -->|"결과 암호문"| E
```

| 설계 요소 | 설명 |
|:---|:---|
| 인코더·암복호화기 | 값을 슬롯에 넣고 암호화·복호화 |
| 키·파라미터 저장소 | 키·차수·모듈러스·보안수준 보관 |
| 동형 평가 엔진 | 암호문 상태에서 회로 실행 |
| 노이즈·레벨 관리자 | 재선형화·스케일·깊이 추적 |

> 요약: 소유자는 키를 보유하고 서버는 암호문만 계산

### 쉽게 이해하기 (학습용)

- 한 상자에 여러 숫자를 칸별로 넣으면 서버가 한 번의 암호문 연산으로 모든 칸에 같은 계산을 적용해 비용을 나눌 수 있다.

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant O as 데이터 소유자
    participant E as 동형 평가 서버
    O->>O: 키·파라미터 생성
    O->>E: 입력 암호문·평가 키 전달
    O->>E: 평가 회로 요청
    E->>E: 암호문 회로 평가
    E-->>O: 결과 암호문 반환
    O->>O: 결과 복호화·오차 검증
```

| 절차 | 설명 |
|:---|:---|
| 키·파라미터 생성 | 회로 깊이·보안·오차 한도 반영 |
| 입력 암호문·평가 키 전달 | 원문·비밀키 없이 계산 준비 |
| 평가 회로 요청 | 허용 연산과 출력 형식 지정 |
| 암호문 회로 평가 | 노이즈·레벨을 관리하며 계산 |
| 결과 암호문 반환 | 복호화 전 계산 결과 전달 |
| 결과 복호화·오차 검증 | 평문 결과와 허용 오차 판정 |

> 요약: 회로 깊이에 맞춘 키로 암호문 계산

### 쉽게 이해하기 (학습용)

- 계산 도중 노이즈 예산이 다 떨어지면 결과를 열 수 없으므로, 실행할 곱셈 깊이를 먼저 정하고 키와 파라미터를 만들어야 한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | BFV | BGV | CKKS |
|:---|:---|:---|:---|
| 핵심 특징 | 정확한 정수·모듈러 연산 | 레벨별 정확한 정수 연산 | 실수·복소수 근사 연산 |
| 적용 기준 | 정확한 합계·횟수 계산 | 깊은 정수 회로 계산 | 통계·기계학습 추론 |
| 주요 위험 | 깊이에 따른 파라미터 증가 | 레벨 관리 복잡성 | 스케일 오류·근사 오차 누적 |

> 요약: 정수 정확도·실수 오차·깊이로 방식 선택

### 쉽게 이해하기 (학습용)

- 한 건도 틀리면 안 되는 정수 집계는 BFV·BGV를 쓰고, 작은 오차를 허용하는 실수 통계와 기계학습은 CKKS를 쓴다.

## Ⅵ. 실무 사례

1. 의료 통계는 CKKS로 암호화 평균 계산
2. 암호화 건수 집계는 BFV로 정확 계산

### 쉽게 이해하기 (학습용)

- 의료기관은 환자 값을 암호화한 채 외부 서버에서 평균을 계산하고, 허용 오차 안의 결과만 복호화해 원문 노출을 줄인다.
- 투표나 거래 건수처럼 정확한 정수가 필요한 집계는 BFV를 사용해 근사 오차 없이 암호문 합계를 계산한다.

## Ⅶ. 결론

- 데이터형·회로 깊이·허용 오차로 방식 선택

### 쉽게 이해하기 (학습용)

- 원문을 숨긴 채 계산할 수 있어도 계산 회로와 결과가 맞다는 보장은 없으므로, 데이터형·깊이·오차에 맞는 방식과 별도 결과 검증을 정해야 한다.
