## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **공유 책임 모델**: 클라우드 제공자와 고객이 서비스 계층별 보안 통제의 수행•증명 책임을 나누는 원칙이다.
- **책임 공백**: 제공자와 고객 어느 쪽에도 특정 통제의 수행 책임이 지정되지 않은 상태이다.

</details>

- 정의/개념: **공유 책임 모델**은 서비스 계층별 통제의 수행•증명 책임을 제공자와 고객에게 할당한다.
- 배경/필요성: 제공자가 보안 전체를 맡는다는 오해는 **책임 공백**을 만든다.

#### 한줄 요약

- 클라우드를 빌려도 보안 전체를 맡긴 것은 아니므로 건물 관리와 입주자 관리처럼 각자 해야 할 일을 통제별로 나눠야 한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **통제 소유권**: 각 보안 통제를 수행하고 결과를 증명할 제공자 또는 고객 책임 주체를 지정하는 것이다.
- **운영 증적**: 설정•로그•감사 보고서처럼 통제가 실제 수행되었음을 입증하는 자료이다.

</details>

- **통제 소유권**으로 제공자•고객의 수행 책임을 지정한다.
- IaaS•PaaS•SaaS에 따라 고객 관리 범위가 달라진다.
- 계약•설정•로그 같은 **운영 증적**으로 책임 이행을 확인한다.

#### 한줄 요약

- 제공자가 서버를 안전하게 운영해도 고객이 관리자 계정이나 공개 공유 설정을 잘못 관리하면 데이터는 여전히 노출된다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **공동 통제**: 제공자와 고객이 각자 맡은 부분을 수행해야 완성되는 통제이다.
- **상속 통제**: 제공자의 수행 결과를 고객 통제의 일부로 활용하는 통제이다.
- **서비스 수준 협약(Service Level Agreement, SLA)**: 가용성•지원•복구 수준과 책임 범위를 정한 계약이다.
- **사고 인터페이스**: 제공자와 고객의 탐지•통보•조사•복구 협업 절차이다.

</details>

```text
                     [서비스•계약 경계]
                       /             \
                [제공자 통제]     [고객 통제]
                       \             /
                     [공동•상속 통제]
                              |
                    [증적•사고 인터페이스]
```

선의 의미: 서비스•계약 경계 아래 제공자와 고객 통제를 분리하고, 양측의 공동•상속 통제와 증적•사고 협업 접점을 연결한 정적 책임 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 서비스•계약 경계 | 기능•**SLA**•제외 책임 정의 |
| 제공자 통제 | 시설•하드웨어•관리 계층 보호 |
| 고객 통제 | 계정•데이터•앱 설정 보호 |
| 공동•상속 통제 | **공동 통제**•**상속 통제**의 책임 분담 |
| 증적•사고 인터페이스 | 운영 증적과 **사고 인터페이스** 연결 |

#### 한줄 요약

- 계약으로 경계를 정하고 양측 통제를 이어 붙인 뒤 감사 자료와 사고 대응 절차로 실제 수행 여부를 확인한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **책임 할당 행렬(Responsible, Accountable, Consulted, Informed, RACI)**: 통제별 수행•책임•협의•통보 주체를 구분하는 행렬이다.
- **책임 검증 계획**: 양측의 통제 수행 결과를 어떤 증거와 주기로 확인할지 정한 계획이다.
- **제공자 통제•증적 추출**: 제공자가 보호하는 하부 계층의 범위와 감사 근거를 구성하는 단계이다.
- **고객 통제•소유자 정의**: 고객이 맡은 계정•데이터•설정 통제의 담당자를 지정하는 단계이다.
- **서비스 계층•책임 경계 매핑**: 통제를 제공자•고객•공동 책임으로 분류하는 단계이다.
- **RACI•책임 검증 계획 수립**: 통제별 수행•책임•협의•통보 주체와 증거 확인 방법을 정하는 단계이다.
- **증적 검증•책임 공백 개선**: 수행 결과를 확인하고 누락된 책임과 사고 절차를 보완하는 단계이다.

</details>

```text
[서비스•계약 경계]
          |
          +-- [클라우드 제공자]
          |          |
          |          v
          |   1. 제공자 통제•증적 추출 --+
          |                               |
          `-- [클라우드 고객]             |
                     |                    |
                     v                    |
              2. 고객 통제•소유자 정의 --+
                                          |
                                          v
                                [통제 거버넌스]
                                          |
                                          v
                         3. 서비스 계층•책임 경계 매핑
                                          |
                                          v
                         4. RACI•책임 검증 계획 수립
                                          |
                                          v
                                 [감사•사고 대응]
                                          |
                                          v
                         5. 증적 검증•책임 공백 개선
                                          |
                                          `-- 공백•사고 개선 결과
```

### 동작 원리

1. **제공자 통제•증적 추출**: 하부 계층 보호 범위에서 제공자 통제•증적을 추출한다.
2. **고객 통제•소유자 정의**: 계정•데이터•설정의 고객 통제•소유자를 정의한다.
3. **서비스 계층•책임 경계 매핑**: 제공자•고객•공동 통제로 서비스 계층•책임 경계를 매핑한다.
4. **RACI•책임 검증 계획 수립**: 승인•협의•증거 확인 방법을 포함한 RACI•책임 검증 계획을 수립한다.
5. **증적 검증•책임 공백 개선**: 증적을 검증하고 책임 공백을 개선한다.
#### 한줄 요약

- **RACI**와 **책임 검증 계획**으로 통제와 증거를 연결해 사고 때 책임 전가를 막는다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **서비스형 인프라(Infrastructure as a Service, IaaS)**: 고객이 OS부터 상위 계층을 관리하는 클라우드 서비스이다.
- **서비스형 플랫폼(Platform as a Service, PaaS)**: 고객이 애플리케이션부터 상위 계층을 관리하는 클라우드 서비스이다.
- **서비스형 소프트웨어(Software as a Service, SaaS)**: 고객이 계정•데이터•업무 설정을 관리하는 클라우드 서비스이다.
- **운영체제(Operating System, OS)**: 하드웨어 자원과 응용 실행 환경을 관리하는 시스템 소프트웨어이다.

</details>

| 클라우드 책임 유형 | 공유 책임 공통 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|:---|
| 적용 기준 | 클라우드 통제 소유권 정의 | 높은 구성 자유도 | 개발 플랫폼 활용 | 완성 업무 기능 사용 |
| 핵심 특징 | 제공자•고객 계층 분담 | **IaaS**는 고객이 **OS**부터 관리 | **PaaS**는 고객이 앱부터 관리 | **SaaS**는 고객이 계정•데이터 관리 |
| 한계 | 책임 공백•증적 단절 | 패치•망 설정 오류 | 비밀•권한 구성 오류 | 계정•공유 설정 오류 |

#### 한줄 요약

- 서비스형 인프라는 고객이 관리할 층이 가장 많고 서비스형 플랫폼와 서비스형 소프트웨어로 갈수록 줄지만 계정•데이터•업무 설정 책임은 계속 남는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-145**: 클라우드 서비스와 배치 모델을 정의하는 미국 국립표준기술연구소 지침이다.
- **ISO/IEC 27017:2015**: 클라우드 제공자와 고객의 역할별 정보보호 통제를 제시하는 국제 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 서비스 모델별 경계 혼선 | **NIST SP 800-145** 기준 분류 | IaaS•PaaS•SaaS의 책임 정렬 |
| 제공자•고객 통제 편차 | **ISO/IEC 27017:2015** 적용 | 역할•구현의 지침 명확화 |
| 증적•사고 협업 공백 | **RACI**•**SLA**•로그 제공 명시 | 책임 전가와 대응 지연 방지 |

#### 한줄 요약

- 클라우드 제공자는 저장 인프라를 보호하지만 고객은 버킷 공개 여부와 사용자 권한을 설정•점검해야 하므로 양측 책임을 통제표에 명시한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **통제별 책임 완결성**: 모든 통제에 수행 주체•최종 책임•증거•사고 협업 절차가 빠짐없이 지정된 상태이다.

</details>

- **통제별 책임 완결성**을 확보하고 **IaaS**•**PaaS**•**SaaS**는 OS•앱•계정부터 각각 고객 책임으로 지정한다.

#### 한줄 요약

- 공유 책임은 사고 책임을 나누는 면책 문구가 아니라 각 통제를 누가 어떻게 수행하고 무엇으로 증명할지 정하는 운영 기준이다.
