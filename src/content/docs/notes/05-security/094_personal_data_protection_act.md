## 미리 알고가기

- **정보주체**: 자신의 개인정보 처리에 권리를 행사함
- **개인정보처리자**: 목적·항목·방법을 결정하고 의무를 부담함
- **수탁자**: 처리자 지시에 따라 위탁 업무를 수행함
- **데이터베이스(Database, DB)**: '디비'로 읽고 영문 머리글자로 개인정보 원본·복제본을 구조화해 저장하는 저장소를 표시
- **제3자 제공**: 제공받는 자가 자신의 목적에 개인정보를 사용하도록 이전하는 처리
- **처리 위탁**: 개인정보처리자의 업무 목적을 수탁자가 대신 수행하도록 맡기는 처리
- **안전조치**: 접근 통제·암호화·접속기록 등 개인정보 유출·변조를 줄이는 보호조치
- **보유기간**: 처리 목적이나 법적 의무에 따라 개인정보를 보관할 수 있는 기간



## Ⅰ. 개요

- **정의/개념**: 개인정보 처리와 권리·의무를 정한 일반법이다
- **배경/필요성**: 처리 전 과정의 목적·근거·기간 위반을 막는다

### 쉽게 이해하기 (학습용)
- 정보를 어디서 모아 누구와 쓰고 언제 지울지 통제함

## Ⅱ. 특징

- 목적·근거 확인은 목적 외 처리와 무단 이용을 막는다
- 최소 수집·보존은 유출 시 개인정보 피해를 줄인다
- 단계별 책임은 제공·위탁의 통제 공백을 막는다
- 안전조치는 유출·변조와 무단 접근 피해를 줄인다
- 권리 요청 처리는 정보주체의 통제권을 보장한다

### 쉽게 이해하기 (학습용)

- 처리 목적과 근거를 정하고 필요한 정보만 받아 단계마다 책임을 나눔

## Ⅲ. 아키텍처 및 구성요소

```mermaid
flowchart LR
    S[정보주체] --> C[수집·이용 처리자]
    C --> T[제3자 제공]
    C --> O[처리 위탁]
    C --> D[저장·복제본]
    T --> P[기간 종료·파기]
    O --> P
    D --> P
```

| 설계 요소 | 설명 |
|:---|:---|
| 목적·근거부 | 목적·항목·근거·기간 연결 |
| 수집 계층 | 필수·선택 항목 고지·동의 |
| 이전 게이트 | 제3자 제공·위탁 근거 검사 |
| 안전 계층 | 접근통제·암호화·접속기록 집행 |
| 파기 계층 | 기간 만료 원본·복제본 삭제 |

> 요약: 처리 목적·근거를 원본과 복제본까지 통제한다

### 쉽게 이해하기 (학습용)

- 수집한 정보가 제공·위탁·복제되는 모든 경로에 같은 목적과 기간을 연결함

## Ⅳ. 원리 및 절차 흐름도

```mermaid
sequenceDiagram
    participant S as 정보주체
    participant C as 개인정보처리자
    participant T as 제3자·수탁자
    participant D as 저장소
    S->>C: 목적·근거 확정
    C->>S: 최소 수집
    C->>T: 이용·이전 통제
    S->>C: 권리 요청
    C->>D: 보유 종료·파기
```

| 절차 | 설명 |
|:---|:---|
| 목적·근거 확정 | 목적·항목·기간 근거 확정 |
| 최소 수집 | 필요한 항목만 수집 |
| 이용·이전 통제 | 제공·위탁 근거 검사 |
| 권리 요청 | 열람·정정·삭제 요구 처리 |
| 보유 종료·파기 | 법정 보존분 제외 후 삭제 |

> 요약: 근거 확정 뒤 단계별 통제와 파기를 수행한다

### 쉽게 이해하기 (학습용)

- 먼저 처리 근거를 정한 뒤 이용·이전·보호·파기를 순서대로 확인함

## Ⅴ. 종류 및 비교

| 판단 기준 | 수집·이용 | 제3자 제공 | 처리 위탁 |
|:---|:---|:---|:---|
| 핵심 특징 | 처리자가 자신의 목적에 사용 | 수령자가 자신의 목적에 사용 | 수탁자가 위탁자의 업무 목적을 대행 |
| 적용 기준 | 목적·법적 근거로 최소 수집할 때 | 제공받는 자·목적·항목·기간을 정할 때 | 계약·공개·수탁자 감독이 필요할 때 |
| 주요 위험 | 목적 외 이용·과다 수집·과도 보유 | 재제공·수령자 통제와 이력 누락 | 재위탁·과도 권한·사고 통지 누락 |

> 요약: 처리 관계별 근거를 확인하고 책임을 분리한다

### 쉽게 이해하기 (학습용)

- 직접 이용·제3자 제공·위탁은 목적과 책임 주체가 서로 다름

## Ⅵ. 실무 사례

1. 회원 정보는 목적별 항목·기간 등록 뒤 파기한다
2. 위탁 계약에 처리 범위·사고 통지를 명시한다

### 쉽게 이해하기 (학습용)

- 회원 정보는 목적별 항목·보유기간을 등록하고 탈퇴·법정 보존 때 파기 상태를 나눔
- 위탁 계약에는 처리 범위·재위탁·사고 통지·종료 후 파기와 수탁자 점검을 포함함

## Ⅶ. 결론

- 목적·근거를 데이터 흐름에 연결해 전 과정을 통제한다.

### 쉽게 이해하기 (학습용)

- 수집 화면뿐 아니라 제공·위탁·복제·파기까지 같은 목적과 근거를 추적해야 함
