## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **차량 사이버보안 및 V2X 통신(Vehicle Cybersecurity & V2X / ISO/SAE 21434 & UN R155)**: 커넥티드 자율주행 차량(CAV)의 외부 무선 통신망(V2X: V2V 차대차, V2I 차대인프라, V2N 차대네트워크), 인포테인먼트(IVI), 텔레매틱스(TCU), OBD-II 진단 포트 및 무선 소프트웨어 업데이트(OTA) 경로를 통해 유입되는 사이버 위협을 방어하고, 차량 내부 제어망(CAN, 이더넷) 및 구동계 ECU(조향/제동)의 물리적 안전성을 차량 전 수명주기(Lifecycle)에 걸쳐 보증하는 보안 체계.
- **외부 무선 통신 침투를 통한 차량 물리 제어권 탈취 결함(Wireless-to-CAN Pivot Defect)**: 차량 내부 CAN 버스는 보안 인증이 없는 평문 브로드캐스트 통신을 사용하므로, 공격자가 셀룰러/Wi-Fi/V2X 인터페이스의 취약점을 통해 IVI나 TCU를 장악한 후 내부 게이트웨이를 우회(Pivot)하여 전자제어장치(ECU)에 악성 조향/제동 제어 패킷을 주입하는 치명적 구조적 결함.

</details>

- 정의/개념: 자율주행 차량의 안전성을 보증하기 위해 **TARA 기반 위협 분석 $\rightarrow$ UN R155 CSMS 및 UN R156 SUMS 형식승인 $\rightarrow$ V2X 3단계 다중 검증(서명 $\rightarrow$ 신선도 $\rightarrow$ 물리적 개연성) $\rightarrow$ 보안 게이트웨이(Security Gateway) 도메인 격리 $\rightarrow$ 차량 EDR/IDS 관제** 를 집행하는 **차량 전주기 사이버보안 엔지니어링 아키텍처**
- 배경/필요성: 차량 내부 제어망(CAN Bus)은 보안 인증이 결여된 평문 브로드캐스트 방식으로 동작하여 외부 셀룰러, Wi-Fi, V2X 무선 통신 인터페이스가 해킹될 경우 중앙 게이트웨이를 우회(Pivot)하여 조향 및 제동 ECU에 악성 제어 패킷을 직접 주입하는 물리적 인명 사고 위협이 상존함에 따라, ISO/SAE 21434 및 UNECE UN R155(CSMS)/R156(SUMS) 국제 법규에 기반하여 전 수명주기 TARA 위협 분석, 중앙 보안 게이트웨이(CSGW) 도메인 격리, AUTOSAR SecOC(메시지 인증 코드 MAC) 및 V2X 3단계 신뢰 검증(디지털 서명 $\rightarrow$ 타임스탬프 신선도 $\rightarrow$ 센서 물리적 개연성)을 결합하는 차량 사이버보안 아키텍처를 도입하여 **외부 무선 침입의 내부 제어망 전이 원천 차단, V2X 악의적 기만 메시지 무력화 및 자율주행 차량 전 수명주기 물리 안전성**을 달성할 필요

#### 한줄 요약
- ISO/SAE 21434와 UN R155/R156 법규를 바탕으로 V2X 다중 검증과 내부 CAN 게이트웨이 보안을 확립한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **차량 사이버보안 3대 핵심 글로벌 법규 및 프레임워크**:
  - **ISO/SAE 21434 (Road vehicles - Cybersecurity engineering)**: 차량 기획, 설계, 개발, 생산, 운영, 유지보수, 폐기까지 전 수명주기에 걸친 사이버보안 프로세스 국제 표준.
  - **UN Regulation 155 (UN R155 / CSMS)**: 차량 제조사의 사이버보안 관리체계(CSMS) 구축 및 차량 형식승인(Type Approval) 의무화 규정.
  - **UN Regulation 156 (UN R156 / SUMS)**: 차량 무선 소프트웨어 업데이트(OTA)의 안전성과 무결성을 보증하는 소프트웨어 업데이트 관리체계(SUMS) 규정.

</details>

- 설계부터 운영까지 **TARA** 기반 전주기 위험 추적
- 서명·신선도·센서를 대조하는 **V2X 다중 검증**
- 외부 통신망과 제어망 사이 **보안 게이트웨이** 격리

#### 한줄 요약
- 전 수명주기 TARA 위험 관리, UN R155/R156 형식승인, V2X 3단계 신뢰 검증, 도메인 분리 게이트웨이를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **차량 사이버보안 5대 핵심 아키텍처 컴포넌트**:
  1. **V2X SCMS (Security Credential Management System)**: 익명성 보장 단기 가명 인증서(Pseudonym Certificate) 발급 PKI.
  2. **Central Security Gateway (CSGW)**: 방화벽, 라우팅, 메시지 화이트리스트 필터링.
  3. **In-Vehicle Network (SecOC)**: AUTOSAR SecOC(Secure Onboard Communication) 기반 CAN-FD MAC 인증.
  4. **Hardware Security Module (HSM)**: ECU 내부 전용 암호 가속기 및 키 저장소.
  5. **Vehicle Security Operations Center (vSOC)**: 커넥티드 차량 플릿(Fleet) 이상 징후 원격 관제.

</details>

```text
차량 사이버보안 경계
├─ 외부 연결
│  └─ V2X SCMS·TCU·OTA
├─ 중앙 보안 경계
│  └─ 보안 게이트웨이
├─ 차량 제어 경계
│  ├─ AUTOSAR SecOC·ECU HSM
│  └─ 차량 EDR·CAN-IDS
└─ 관제 경계
   └─ vSOC·CSMS·SUMS
```

선의 의미: 외부 무선 트래픽이 보안 게이트웨이(CSGW)에서 필터링된 후 AUTOSAR SecOC를 통해 내부 ECU로 전달되며, vSOC에서 플릿을 관제하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **V2X SCMS·TCU·OTA** | 가명 인증서와 암호 통신으로 외부 연결 보호 |
| **보안 게이트웨이** | 외부 통신망과 내부 CAN 제어망 격리 |
| **AUTOSAR SecOC·ECU HSM** | MAC 인증과 안전한 암호키 저장 |
| **차량 EDR·CAN-IDS** | 제어 버스의 이상 트래픽 탐지 |
| **vSOC·CSMS·SUMS** | 차량군 관제와 안전한 원격 갱신 |

#### 한줄 요약
- CAN 제어망은 내부에 들어온 메시지를 무조건 신뢰하도록 설계됐으므로, 보안 게이트웨이가 외부 연결과 제어망 사이에 없던 경계를 세우고 SecOC가 그 신뢰 전제를 메시지마다의 MAC 검증으로 대체하며 키 보관 부담은 ECU HSM이 떠맡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **V2X 메시지 3단계 신뢰 검증 및 제어 프로세스**:
  1. 외부 선행 차량으로부터 V2X 긴급 제동 경고(EEBL) 수신
  2. IEEE 1609.2 기반 디지털 서명 및 인증서 유효성 검증 (1단계)
  3. 타임스탬프 및 위치 기반 신선도(Freshness) 검증 (2단계)
  4. 로컬 라이다/레이더 센서 데이터와의 물리적 개연성(Plausibility) 대조 (3단계)
  5. 최종 검증 성공 시 제동 ECU 구동 또는 기만 메시지 식별 시 폐기 및 vSOC 보고

</details>

```text
[V2X 송신자] ── 긴급 제동 경고 ──> [차량 검증기]
            │
            ▼
1. [전자서명 검증]
    ├─ SCMS 가명 인증서 체인 유효성 및 IEEE 1609.2 ECDSA 서명 검증
    └─ [서명 위조 또는 만료 인증서 확인 시 ➔ 즉시 폐기]
            │
            ▼
2. [신선도 검증]
    ├─ 메시지 타임스탬프와 현재 수신 시각 간의 시차(Delta-T) 계산
    └─ [시차 > 100ms (재전송 공격 의심) ➔ 메시지 폐기]
            │
            ▼
3. [물리적 개연성 검사]
    ├─ 수신된 선행차 위치/속도 좌표 vs 내 차 전방 라이다/레이더 실측 거리 대조
    └─ [물리적 모순 발생(예: 라이다에 전방 차량 없음) ➔ 센서 스푸핑 이상 징후 판정]
            │
            ▼
4. [안전 제동 또는 차단]
    ├─ [3단계 검증 100% 통과] ➔ 중앙 게이트웨이 ➔ SecOC CAN 메시지로 제동 ECU 전달 (감속)
    └─ [개연성 불일치 시] ➔ 메시지 차단 + 이상 송신자 가명 인증서를 클라우드 vSOC에 보고 (블랙리스트 등록)]
```

**동작 원리**

1. **전자서명 검증**: SCMS 인증서와 ECDSA 서명 확인
2. **신선도 검증**: 타임스탬프로 재전송 메시지 폐기
3. **물리적 개연성 검사**: 센서 실측값과 위치·속도 대조
4. **안전 제동 또는 차단**: 정상 메시지만 ECU에 전달

#### 한줄 요약
- 검증 단계를 늘릴수록 위조 메시지는 잘 걸러지지만 제동 판단까지의 지연이 함께 늘어나므로, V2X 검증은 밀리초 단위 시간 예산 안에서 순서를 짜야 한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **V2X 3대 통신 유형 비교**:
  - V2V (Vehicle-to-Vehicle): 차량 간 직통 충돌 방지 통신 (초저지연, 인프라 불필요).
  - V2I (Vehicle-to-Infrastructure): 차량과 신호등/RSU 간 통신 (도로 교통 제어).
  - V2N (Vehicle-to-Network): 차량과 5G 클라우드 간 광대역 통신 (OTA, 원격 진단).

</details>

| 비교 항목 | 차량 대 차량 (V2V) | 차량 대 도로 인프라 (V2I) | 차량 대 네트워크 (V2N) |
|:---|:---|:---|:---|
| **통신 형태** | **차량 간 직접 무선 통신 (Direct Ad-hoc)**| **차량 ↔ 노변 기지국 (RSU) 통신** | **차량 ↔ 이동통신망 ↔ 클라우드** |
| **요구 레이턴시** | **초저지연 (수 ms 이내 즉시 반응)** | 저지연 (수십 ms 이내) | 일반 (수백 ms ~ 수 초 허용) |
| **핵심 서비스** | **긴급 제동 경고(EEBL), 교차로 충돌 방지**| 신호등 잔여 시간 안내, 공사 구간 경고| **원격 펌웨어 OTA 갱신, vSOC 관제** |
| **주요 위협** | **가짜 사고 메시지 주입, Sybil 공격** | 노변 RSU 장악을 통한 신호 조작 | **클라우드 API 탈취, 전 차량 원격 조작**|
| **핵심 보안 대책** | **SCMS 가명 인증서, 물리 개연성 검사** | RSU 하드웨어 탬퍼링 방어, TLS | **mTLS 1.3 통신, SUMS 버전 무결성 검증**|

#### 한줄 요약
- V2V는 초저지연 안전 제어, V2I는 도로 인프라 연계, V2N은 클라우드 원격 관제 및 OTA에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/SAE 21434 및 UN R155/R156**: 차량 사이버보안 엔지니어링 및 UNECE 유럽 형식승인 법규.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 차량 설계 단계에서 TARA 위험 평가를 누락하여 **유럽 경제 위원회(UNECE) UN R155 형식승인 심사에서 탈락 및 신차 수출 전면 중단** | **ISO/SAE 21434 표준 준수, 전 전장 부품에 대한 TARA(위협 분석) 수행 및 본사 CSMS 인증 획득** | 유럽 및 글로벌 신차 판매 형식승인 100% 획득 |
| 공격자가 외부 통신 모듈(TCU)을 해킹한 후 내부 CAN 버스에 위조 제동 명령을 주입하여 **고속 주행 중인 차량의 브레이크를 임의 작동시키는 사고 발생** | **중앙 보안 게이트웨이(CSGW) 기반 도메인 격리 및 AUTOSAR SecOC 메시지 인증 코드(MAC) 적용** | 비인가 CAN 메시지 주입 및 원격 차량 탈취 100% 원천 차단 |
| 대규모 OTA 펌웨어 업데이트 중 네트워크 오류로 인해 **수만 대 차량의 ECU가 벽돌(Bricking) 상태로 정지하여 전량 리콜 발생** | **UN R156 SUMS 규격 준수, 듀얼 뱅크(A/B) 롤백 파티셔닝 및 ECU 간 펌웨어 버전 종속성 사전 무결성 검증 강제** | OTA 업데이트 장애로 인한 차량 마비 0% 및 안전 롤백 보증 |

#### 한줄 요약
- CSMS/TARA로 수출 승인을 확보하고, SecOC 게이트웨이로 CAN 조작을 막으며, SUMS 듀얼 뱅크로 안전한 OTA를 달성한다.

## Ⅶ. 결론

- 외부 무선 통신망과 내부 전장 제어망을 완벽히 격리하고 메시지 단위의 암호학적·물리적 무결성을 보증하는 **커넥티드 자율주행 차량 사이버보안 및 V2X 신뢰 검증(ISO/SAE 21434 / UN R155·R156 / SecOC & SCMS)의 글로벌 표준 아키텍처**로 확고히 자리 잡았으며, 차량 보안관제(vSOC) 및 양자 내성 암호(PQC) 기반 V2X 통신으로 진화하는 가운데, 실무 커넥티드카 전장 아키텍처 설계 시에는 **UN R155 CSMS 형식승인을 위한 전장 부품 전수 TARA 수행, 외부 통신망과 내부 CAN 제어망 간 중앙 보안 게이트웨이(CSGW) 및 AUTOSAR SecOC MAC 적용, V2X 메시지 수신 시 서명·신선도·라이다 센서 개연성(Plausibility) 3단계 파이프라인 검증**을 결합하여 완벽한 차량 사이버 물리 안전성을 완성

#### 한줄 요약
- ISO/SAE 21434 표준과 UN R155/R156 법규 준수 및 V2X 3단계 신뢰 검증을 통해 완벽한 차량 사이버보안을 완성한다.
