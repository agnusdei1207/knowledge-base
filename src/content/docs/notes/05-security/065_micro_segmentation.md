## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **마이크로 세그멘테이션(Micro-Segmentation)**: 전통적인 외부 네트워크 경계(Perimeter) 방어에 의존하지 않고, 데이터센터 및 클라우드 내부의 가상 머신(VM), 컨테이너, 베어메탈 워크로드 단위로 네트워크 세그먼트를 극도로 세분화하여, 워크로드 간의 동서(East-West) 트래픽에 대해 명시적으로 승인된 1:1 통신만 허용하는 제로 트러스트 보안 통제 기법.
- **동서 트래픽 가시성 부재 및 횡적 이동(East-West Visibility Blind Spot Defect)**: 전통적인 방화벽은 남북(North-South / 인바운드-아웃바운드) 트래픽만 감시하므로, 동일 VLAN 또는 서브넷 내부 서버 간의 동서 트래픽을 통제하지 못하여 공격자가 내부 서버 1대를 장악한 후 랜섬웨어를 전사 확산시키는 구조적 결함.

</details>

- 정의/개념: NIST SP 800-125B 및 800-207 표준에 기반하여 통신 흐름 가시성(Flow Visibility) 확보 $\rightarrow$ 메타데이터 라벨(Label) 기반 신원 부여 $\rightarrow$ 중앙 정책 관리면(Control Plane) 화이트리스트 배포 $\rightarrow$ 호스트 커널(eBPF/Iptables) 분산 집행(Distributed Enforcement) $\rightarrow$ 기본 거부(Default Deny) 를 집행하는 워크로드 격리 아키텍처
- 배경/필요성: 데이터센터 및 클라우드 트래픽의 80% 이상을 차지하는 동서(East-West / 내부 워크로드 간) 트래픽에 대해 기존의 남북(North-South) 경계 방화벽만으로는 내부 가시성을 확보할 수 없고, 동일 VLAN/서브넷 내 단일 서버 침해 시 랜섬웨어가 전체 내부망으로 급속히 확산되는 횡적 이동(Lateral Movement) 취약점이 발생함에 따라, 가변적인 IP 대신 불변의 워크로드 메타데이터 라벨(Label)과 호스트 커널 레벨(eBPF/Iptables)의 분산 패킷 필터링을 결합하는 NIST SP 800-125B 및 800-207 **마이크로 세그멘테이션** 아키텍처를 도입하여 내부 동서 트래픽의 100% 가시성 확보, 기본 거부(Default Deny) 기반의 워크로드 1:1 최소 권한 통제 및 침해 폭발 반경(Blast Radius)의 극단적 축소를 달성할 필요

#### 한줄 요약
- 마이크로 세그멘테이션의 값어치는 차단 성능이 아니라 통제 기준을 위치(IP)에서 정체성(라벨)으로 옮겨 인프라가 바뀌어도 정책이 따라붙게 만든 데 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **라벨 기반 정책(Identity/Label-based Policy)**: 가변적인 IP 주소 대신 `app: payment`, `env: prod`, `tier: db`와 같은 불변의 메타데이터 태그(라벨)를 기준으로 접근 통제 정책을 선언하여 오토스케일링 및 컨테이너 재기동 시에도 보안 정책을 자동 유지하는 기술.
- **분산 집행(Distributed Enforcement / Host-level eBPF)**: 중앙 방화벽 장비로 모든 트래픽을 헤어핀(Hairpinning) 라우팅하지 않고, 개별 호스트 OS 커널(eBPF, Windows Filtering Platform)에서 분산 패킷 필터링을 직접 수행하여 병목을 제거하는 아키텍처.

</details>

- 동서(East-West) 트래픽의 전수 통제: 데이터센터 전체 트래픽의 80% 이상을 차지하는 내부 서버 간 통신을 제로 트러스트 수준으로 검증
- 기본 거부(Default Deny) 기반 화이트리스트: 명시적으로 허용된 특정 포트/프로토콜 통신 외의 모든 미인가 내부 패킷 즉시 드롭
- 인프라 비종속성 (Software-Defined & Overlay): 물리 스위치나 라우터의 재구성 없이 소프트웨어 오버레이 및 호스트 에이전트/eBPF로 구현

#### 한줄 요약
- 네 특징은 통신 의존성을 사전에 전수 파악해야 하는 부담을 지는 대가로, 중앙 방화벽 병목 없이 폭발 반경을 워크로드 단위까지 줄인 결과다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **마이크로 세그멘테이션 4대 핵심 계층**:
  1. **가시성 및 맵핑 계층**: 워크로드 간 실시간 통신 맵 생성 (Flow Mapping).
  2. **중앙 제어 평면 (Control Plane)**: 전사 라벨링 및 XACML/선언적 정책 관리.
  3. **분산 데이터 평면 (Data Plane)**: 호스트 eBPF/가상 스위치 인라인 패킷 필터링.
  4. **감사 및 텔레메트리 계층**: 미인가 패킷 드롭 및 정책 위반 실시간 SIEM 스트리밍.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 중앙 정책 관리면 (Control Plane: Policy Management & Visibility) ]  │
│  ├─ 통신 흐름 가시성 분석: 워크로드 간 실시간 의존성 토폴로지 매핑     │
│  ├─ 메타데이터 라벨 정의: `Role=Web`, `Role=DB`, `Env=Prod`              │
│  └─ [ 화이트리스트 규칙 선언: `Web -> DB (TCP 3306) 허용, 그 외 ALL Deny`]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (정책 동기화 및 룰셋 배포)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 분산 집행 데이터 평면 (Distributed Data Plane: Host / eBPF) ]      │
│                                                                         │
│  ┌──────────────────────┐   (동서 트래픽: TCP 3306)   ┌──────────────────────┐  │
│  │ [ 웹 워크로드 (Web) ] ├────────────────────────────▶│ [ DB 워크로드 (DB) ]  │  │
│  │  └─ eBPF 분산 방화벽 │                            │  └─ eBPF 분산 방화벽 │  │
│  └──────────┬───────────┘                            └──────────────────────┘  │
│             │ (비인가 횡적 이동 시도: SSH/SMB 포트 스캔)                          │
│             ▼                                                                   │
│  [ 차단: eBPF 커널 레벨 즉각 드롭 ➔ SIEM 이상 징후 실시간 경보 스트리밍 ]        │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 중앙 제어 평면이 라벨 기반 화이트리스트 정책을 배포하면, 개별 호스트의 eBPF 데이터 평면이 동서 트래픽을 커널 레벨에서 분산 필터링하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| 통신 흐름 가시성 엔진 | 워크로드 간의 실제 네트워크 트래픽을 관찰하여 통신 의존성 지도를 자동 생성 | Flow Visibility|
| 라벨 관리자 (Labeler) | CSP(AWS/Azure), K8s, CMDB와 연동하여 워크로드 메타데이터 태그를 중앙 동기화 | **Identity** Engine|
| 정책 제어기 (Control Plane)| 선언적 정책(YAML/JSON)을 컴파일하여 수만 대의 분산 호스트로 동기화 배포 | Central Policy |
| **분산 집행**자 (eBPF Agent) | 호스트 OS 커널 레벨에서 패킷을 직접 검사하여 마이크로초 단위로 인라인 필터링 | Distributed DP |
| 보안 감사 텔레메트리 | 허용/차단된 동서 트래픽 로그를 집계하여 오탐 분석 및 침해 지표를 SIEM 전달 | Audit & SIEM |

#### 한줄 요약
- 판단은 중앙에 두고 집행만 호스트 커널로 흩뿌린 덕에 트래픽 헤어핀이 사라지지만, 그만큼 수만 대에 걸친 룰셋 동기화 지연이 새로운 위험 구간이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **마이크로 세그멘테이션 3단계 도입 수명주기**:
  1. **관찰 모드(Observation/Audit)**: 차단 없이 트래픽만 모니터링하여 베이스라인 수립.
  2. **테스트 모드(Soft Enforcement)**: 정책 위반 경고 발생 및 오탐 보정.
  3. **차단 모드(Hard Enforcement)**: Default Deny를 적용하여 미인가 트래픽 즉각 드롭.

</details>

```text
1. [통신 흐름 관찰] 에이전트/eBPF가 데이터센터 내 모든 동서 트래픽을 수집하여 2~4주간 베이스라인 맵 작성
            │
            ▼
2. [라벨링 및 정책 수립] `app: frontend` ➔ `app: backend:8080` 허용 화이트리스트 정책 정의
            │
            ▼
3. [정책 배포 및 동기화] 중앙 제어 평면이 타깃 호스트 커널로 eBPF 필터링 룰셋 일괄 주입
            │
            ▼
4. [분산 인라인 검증 및 집행]
    ├─ 정상 트래픽: Frontend ➔ Backend(8080) 요청 ➔ [커널 레벨 즉시 통과(Pass)]
    └─ 비인가 트래픽: Frontend ➔ 인접 Payment DB(3306) 스캔 시도 ➔ [eBPF 커널 즉각 드롭(Drop)]
            │
            ▼
5. [이상 징후 분석 및 피드백] 차단된 횡적 이동 시도 패킷을 SIEM으로 전송하고 공격 격리 조치 발동
```

1. 사전 영향도 최소화: 관찰 모드를 통해 정상 서비스 간의 의존성을 사전에 100% 파악
2. 동적 오케스트레이션 연동: 컨테이너가 생성/소멸할 때마다 라벨을 추적하여 방화벽 룰 자동 동기화
3. 네트워크 병목 해소: 모든 트래픽이 중앙 장비로 집중되지 않고 발생 지점(Host Kernel)에서 즉시 처리
4. 폭발 반경의 극단적 축소: 단일 웹 워크로드가 장악되더라도 내부 DB나 인접 서버로의 접근 경로 완전 차단
5. 폐쇄 루프 이상 탐지: Default Deny에 의해 드롭된 비정상 동서 트래픽을 내부 침해 지표로 즉각 인지

#### 한줄 요약
- 관찰 모드에 쓰는 2~4주는 낭비가 아니라 Default Deny 전환 시의 오차단 장애 비용을 앞당겨 지불하는 구간이며, 이를 건너뛴 도입이 실패의 전형이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **망 분리 3대 아키텍처 비교**: 네트워크 VLAN(L2/L3 레거시), 호스트 워크로드 정책(L4), 서비스 메시(L7 Sidecar)의 비교.

</details>

| 비교 항목 | 전통 VLAN / Subnet (L2/L3) | 호스트 마이크로 세그멘테이션 (L4) | 서비스 메시 / Sidecar (L7) |
|:---|:---|:---|:---|
| 통제 경계 단위 | 네트워크 서브넷 대역 (거시적 구역) | 개별 VM / OS 호스트 단위 (1:1) | 개별 컨테이너 / API 엔드포인트 단위 |
| 통제 기준 식별자 | 정적 IP 주소, VLAN ID, 서브넷 | 호스트 메타데이터 라벨, 프로세스 | mTLS SPIFFE 신원, HTTP URL 경로 |
| 동서 트래픽 통제 | 동일 서브넷 내부 통제 불가 (자유 통신) | 동일 서브넷 내 호스트 간 완벽 통제 | 동일 파드/노드 내 컨테이너 간 완벽 통제|
| 시스템 오버헤드 | 물리 스위치 ASIC 처리 (오버헤드 0%) | 극히 미미 (호스트 커널 eBPF 고속 처리)| 보통 (Envoy 사이드카 프록시 통신 지연) |
| 적용 권장 환경 | 전통 엔터프라이즈 정적 네트워크 | 하이브리드 클라우드, IaaS, 대규모 VM | 쿠버네티스 클라우드 네이티브 MSA 환경 |

#### 한줄 요약
- VLAN은 서브넷 대역 단위, 호스트 세그멘테이션은 L4 워크로드 1:1 단위, 서비스 메시는 L7 API 단위 통제이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **eBPF(Extended Berkeley Packet Filter)**: 리눅스 커널 소스코드를 수정하거나 모듈을 로드하지 않고도 커널 공간에서 안전하게 샌드박스 프로그램을 실행하여, 마이크로초 단위의 초고속 패킷 필터링과 모니터링을 제공하는 차세대 리눅스 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 레거시 온프레미스와 멀티 클라우드가 혼재되어 전사 일관된 동서 트래픽 세그멘테이션 아키텍처 수립 난항 | NIST SP 800-207 및 800-125B 표준 기반의 소프트웨어 정의 오버레이 및 호스트 에이전트 통합 모델 구축 | 이기종 하이브리드 인프라 전역에 걸친 통일된 마이크로 세그멘테이션 거버넌스 확립 |
| 통신 의존성 파악 없이 '기본 거부(Default Deny)'를 조기 적용하여 사내 핵심 DB 통신이 차단되는 대규모 서비스 장애 | 도입 초기 2~4주간 관찰 모드(Observation Mode)를 선적용하여 통신 베이스라인을 확립한 후 단계적 차단 | 정상 업무 패킷 오차단(False Positive) 0% 달성 및 무중단 제로 트러스트 전환 |
| 수동 라벨링 실수로 인해 신규 배포된 DB 서버의 보안 태그가 누락되어 비인가 통신에 노출되는 결함 발생 | CI/CD IaC 파이프라인 및 CSPM 도구 연동을 통한 워크로드 메타데이터 라벨 자동화 및 무결성 감사 | 라벨 누락으로 인한 통제 사각지대 100% 원천 제거 |

#### 한줄 요약
- 세 대책의 공통 전제는 라벨의 정확성이며, 라벨이 곧 신원인 구조에서는 태그 하나의 누락이 방화벽 규칙 하나의 누락보다 넓은 통제 공백을 만든다.

## Ⅶ. 결론

- 경계가 붕괴된 클라우드 및 가상화 데이터센터 환경에서 내부 침입을 전제(Assume Breach)하고 랜섬웨어와 APT 공격의 횡적 확산을 원천 봉쇄하는 현대 제로 트러스트(Zero Trust) 및 클라우드 워크로드 보안(NIST SP 800-125B)의 핵심 격리 아키텍처로 확고히 안착하였으며, **eBPF** 기반의 초고속 커널 패킷 처리 및 서비스 메시(Service Mesh) L7 mTLS 통합으로 진화하는 가운데, 실무 마이크로 세그멘테이션 구축 시에는 도입 초기 2~4주간 관찰 모드(Observation Mode)를 통한 서비스 간 트래픽 의존성 맵핑 선행, CI/CD 및 CSPM 연동을 통한 워크로드 메타데이터 라벨링 자동화, 중앙 제어 평면의 화이트리스트 배포와 호스트 커널 eBPF 분산 집행의 결합, 점진적 기본 거부(Default Deny) 전환을 결합하여 무결점 무중단 워크로드 격리 생태계를 완성

#### 한줄 요약
- 세그먼트를 잘게 나눌수록 정책 관리 비용도 함께 늘어나므로, 폭발 반경을 어디까지 줄일지는 자원 중요도에 따라 구간별로 다르게 정해야 한다.
