## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모델 서비스 거부(Model Denial of Service / Model DoS / OWASP LLM10:2025)**: 공격자가 100k 토큰 이상의 초장문 컨텍스트 입력, 비대칭적인 고비용 추론 연산 유도, 또는 AI 자율 에이전트의 종료 없는 무한 도구 호출(Tool Loop)을 고의로 발생시켜, LLM 서빙 인프라의 GPU VRAM 메모리, KV 캐시, 스케줄링 큐 및 외부 클라우드 API 과금 예산을 악의적으로 고갈시키는 AI 특화 서비스 거부 공격.
- **비대칭 연산 및 트랜스포머 자원 폭발 결함(Asymmetric Quadratic Complexity Defect)**: 수십만 대의 좀비 PC가 필요한 전통적 네트워크 L4/L7 DoS와 달리, 단 1건의 조작된 프롬프트 요청만으로도 트랜스포머 Self-Attention 행렬 연산량($O(N^2)$)과 KV 캐시 점유량이 기하급수적으로 폭증하여 전체 GPU 클러스터를 마비시키는 구조적 취약점.

</details>

- 정의/개념: 고비용 추론으로 자원을 고갈시키는 **모델 DoS 공격** 방어
- 배경/필요성: 추론 비용이 요청 수가 아니라 문맥 길이에 비대칭적으로 비례해 RPS 쿼터로는 GPU 소모와 과금을 예측할 수 없으므로, 실행 전에 토큰 비용을 추정하는 계측과 **TPM 가중 쿼터·회로 차단기**를 입장 제어 계층으로 앞세운 것

#### 한줄 요약
- 비대칭 $O(N^2)$ 연산과 에이전트 무한 루프로 자원을 고갈시키는 공격을 막기 위해 TPM 가중 쿼터와 회로 차단기를 적용한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비대칭 자원 소비 (Asymmetric Resource Consumption)**: 클라이언트가 전송하는 네트워크 대역폭(수 KB) 대비 서버가 소모해야 하는 GPU 부동소수점 연산(FLOPs)과 VRAM 용량(수십 GB) 간의 비대칭 비율이 수만 배에 달하는 AI 고유 특성.
- **도구 순환 마비 (Infinite Tool Loop / Sponge Attack)**: 에이전트가 종료 조건을 충족하지 못하도록 설계된 모호한 지침을 주입하여, 외부 SQL 쿼리나 유료 결제 API를 수천 번 반복 호출하게 만들어 연동 시스템 마비와 천문학적 요금 폭탄을 유발하는 공격.

</details>

- **트랜스포머 $O(N^2)$ 복잡도 악용**: 컨텍스트 윈도우 길이가 길어질수록 어텐션 연산량과 KV 캐시 메모리가 제곱 비례로 증가하여 GPU 대기열(Queue) 포화
- **멀티 테넌트 공정성 붕괴 (Fairness Collapse)**: 1명의 악의적 사용자가 고비용 연산을 독점함으로써 동일 클러스터를 공유하는 수천 명의 정상 사용자가 타임아웃(504 Error) 피해 직면
- **런타임 회로 차단기(Circuit Breaker) 강제**: 토큰 생성 수량이나 외부 도구 호출 횟수가 사전 임계치를 초과하는 순간 프로세스를 강제 단절하여 시스템 방전 차단

#### 한줄 요약
- $O(N^2)$ 복잡도 악용, 멀티 테넌트 공정성 붕괴, 에이전트 무한 루프 과금 폭탄, 런타임 회로 차단 방어를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모델 DoS 4대 방어 계층**:
  1. **Token Cost Estimator**: 프롬프트 인바운드 수신 시 토큰 길이 및 복잡도 사전 계산기.
  2. **Weighted Admission Controller**: 사용자별 TPM/RPM 잔여 쿼터 대조 및 진입 승인 관문.
  3. **Agent Sandbox Guard**: 에이전트의 도구 호출 횟수(Max Iterations) 제한기.
  4. **Runtime Circuit Breaker**: 무한 루프 감지 시 GPU 연결을 강제 킬(Kill)하는 안전 차단기.

</details>

```text
[ 악의적 사용자 / 공격자 (초장문 100k 토큰 or 무한 루프 유도 프롬프트) ]
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. API 입장 및 사전 비용 추정 계층 (Cost Estimator & Rate Limiter) ]  │
│  ├─ Token Pre-computation: 입력 토큰 수 + 최대 응답 토큰 사전 카운트    │
│  ├─ TPM(Tokens Per Minute) 쿼터 대조: 사용자 잔여 토큰 예산 초과 검사    │
│  └─ [ 쿼터 초과 또는 비정상 초장문 감지 시 ➔ 즉시 429 Too Many Requests] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (승인된 정상 토큰 쿼터 요청)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. GPU 스케줄링 및 테넌트 공정 제어 (Fair-share GPU Scheduler) ]     │
│  └─ vLLM / PagedAttention 기반 메모리 페이징 및 테넌트별 큐 격리 배정   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (추론 실행 및 에이전트 도구 호출)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 런타임 회로 차단 및 축소 응답 계층 (Circuit Breaker & Fallback) ]   │
│  ├─ Tool Loop 감시: 동일 API 반복 호출 5회 초과 시 ➔ [ 도구 실행 강제 킬]│
│  ├─ Time-out & Token Hard Limit: 최대 생성 토큰(예: 4k) 초과 시 강제 종료 │
│  └─ [ GPU 과부하 시 ➔ 경량화 모델(Graceful Degradation)로 임시 스위칭 ] │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 인바운드 요청이 사전 토큰 비용 추정기와 TPM 쿼터를 통과해 공정 스케줄러로 진입하고, 런타임 중 회로 차단기가 폭주를 강제 제어하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **토큰 비용 사전 추정기** | 프롬프트를 GPU 큐에 넣기 전 입력 토큰 및 예상 출력 길이를 계산하여 부하 정량화 | Pre-check |
| **가중 쿼터 입장 제어기** | 단순 RPS가 아닌 분당 토큰 수(TPM)와 모델 체급(FLOPs)을 기준으로 API 호출 제한 | Rate Limiter |
| **테넌트 공정 스케줄러** | PagedAttention을 적용하여 단일 악성 요청이 전체 GPU VRAM을 독점하지 못하도록 격리 | Fair-share |
| **에이전트 반복 제한기** | 에이전트의 최대 도구 실행 횟수(Max Iterations=5)와 재귀 깊이를 엄격 통제 | Agent Guard |
| **런타임 회로 차단기** | 이상 폭주, 타임아웃, 무한 루프 감지 시 GPU 추론 세션을 즉시 강제 종료(Drop) | Circuit Breaker |

#### 한줄 요약
- 토큰 비용 사전 추정기, 가중 쿼터 입장 제어기, 테넌트 공정 스케줄러, 에이전트 반복 제한기, 런타임 회로 차단기가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **모델 DoS 방어 5단계 처리 흐름**:
  1. 프롬프트 수신 및 토큰화(Tokenization) 사전 계측
  2. TPM 쿼터 및 Max Input Token 정책 검증
  3. 공정 스케줄러를 통한 GPU 큐 진입 및 추론 실행
  4. 런타임 도구 실행 횟수 및 생성 토큰 실시간 모니터링
  5. 이상 루프 발생 시 회로 차단기 발동 및 안전 에러 반환

</details>

```text
1. [초장문 DoS 프롬프트 유입] 사용자가 128k 토큰 길이의 무의미한 텍스트 파일 요약 요청 전송
            │
            ▼
2. [사전 토큰 비용 추정 및 쿼터 검사]
    ├─ 게이트웨이가 토큰 길이 계측 (130,000 토큰 확인)
    ├─ 사용자 티어의 Max Input Token 제한(32k 토큰) 및 분당 잔여 TPM(50k) 초과 확인
    └─ [GPU에 도달하기 전 게이트웨이 단에서 즉각 차단(429 Too Many Tokens)]
            │
            ▼ (정상 범위 토큰 내에서 에이전트 무한 루프 공격이 유입된 경우)
3. [GPU 추론 및 에이전트 도구 호출 개시]
    ├─ 모델이 악의적 지시에 넘어가 "종료 없이 데이터베이스 전수 재검색" 반복 시작
    └─ `fetch_db_page(1)` ➔ `fetch_db_page(2)` ➔ `fetch_db_page(3)`...
            │
            ▼
4. [Agent Guard & 회로 차단기(Circuit Breaker) 개입]
    ├─ 도구 반복 호출 횟수가 Max Iteration(10회) 및 실행 시간(30초) 임계치 도달 감지
    └─ [Circuit Breaker가 즉각 발동하여 백엔드 API 연결 및 GPU 스레드 강제 Kill]
            │
            ▼
5. [안전 거부 및 리소스 보존] "도구 호출 한도를 초과했습니다" 반환 및 시스템 자원 100% 보존
```

**동작 원리**

1. **초장문 DoS 프롬프트 유입**
2. **사전 토큰 비용 추정 및 쿼터 검사**
3. **GPU 추론 및 에이전트 도구 호출 개시**
4. **Agent Guard 및 회로 차단기 개입**
5. **안전 거부 및 리소스 보존**

#### 한줄 요약
- 실행 전 계측은 추정이라 오차를 남기고 실행 중 차단은 이미 소모된 GPU 시간을 되돌리지 못하므로, 두 지점 모두에 한도를 걸어야 과금 폭탄을 상한 안에 가둘 수 있다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모델 DoS 3대 공격 유형 비교**: 대량 호출형(Volumetric), 고비용 문맥형(Heavy Context), 에이전트 순환형(Recursive Loop)의 비교.

</details>

| 비교 항목 | 대량 호출형 (Volumetric Flood) | 고비용 문맥형 (Heavy Context) | 에이전트 순환형 (Recursive Loop) |
|:---|:---|:---|:---|
| **공격 메커니즘** | **봇넷을 동원한 무차별 API RPS 폭주** | **1건의 요청에 100k+ 초장문 토큰 주입** | **에이전트가 외부 API를 무한 재귀 호출** |
| **주요 마비 대상** | API Gateway, 웹 프론트엔드 스레드 | **GPU VRAM, KV 캐시, Self-Attention** | **클라우드 API 과금 지갑, 백엔드 DB** |
| **요구 요청 건수** | 수백만 건 (전통 DDoS 형태) | **단 1건~수십 건 (극단적 비대칭성)** | **단 1건 (Sponge Attack)** |
| **핵심 방어 대책** | **L7 WAF, 클라이언트 IP별 RPS 제한**| **토큰 사전 추정기, TPM 가중 쿼터** | **Max Iterations 제한, Circuit Breaker** |

#### 한줄 요약
- 대량 호출형은 네트워크 마비, 고비용 문맥형은 GPU 메모리 고갈, 에이전트 순환형은 무한 과금 유발 공격이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OWASP LLM10:2025 & NIST AI DoS Defense**: LLM 인프라 및 에이전트의 서비스 거부(DoS) 공격 방어와 비용 기반 자원 거버넌스 국제 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공격자가 100k 토큰 이상의 초장문 프롬프트를 전송하여 **GPU KV 캐시 메모리가 방전되고 전체 AI 서빙 클러스터가 다운되는 참사** | **OWASP LLM10:2025** 준수, **사전 토큰 비용 추정기 및 분당 토큰 수(TPM) 기반 가중 쿼터 입장 제어 강제** | 비대칭 고비용 입력의 GPU 큐 진입 100% 원천 차단 및 멀티 테넌트 공정성 보장 |
| AI 자율 에이전트가 악성 프롬프트에 속아 **종료 조건 없이 외부 유료 API와 DB를 무한 반복 호출하여 수억 원의 요금 폭탄 발생** | **에이전트 도구 실행 시 Max Iteration(최대 5회) 제한 및 런타임 회로 차단기(Circuit Breaker) 연동** | 에이전트 무한 루프 및 비정상 API 호출 폭주 발생 즉시 1초 이내 강제 종료 |
| 대규모 합법적 트래픽 집중 또는 분산 DoS 공격으로 인해 **GPU 연산 자원이 포화되어 서비스 전체가 504 타임아웃 에러를 반환하는 결함** | **트래픽 과부하 시 하위 경량화 모델(예: 70B $\rightarrow$ 8B)로 자동 스위칭하는 우아한 축소 응답(Graceful Degradation) 적용** | 시스템 다운타임 제로(Zero) 달성 및 극한의 과부하 상황에서도 최소 필수 서비스 가용성 사수 |

#### 한줄 요약
- TPM 가중 쿼터로 GPU 마비를 막고, 회로 차단기로 과금 폭탄을 방지하며, 축소 응답으로 가용성을 사수한다.

## Ⅶ. 결론

- 입력 비용은 **TPM 쿼터**, 도구 반복은 **회로 차단기**로 제한

#### 한줄 요약
- 토큰 사전 계측과 TPM 가중 쿼터 및 런타임 회로 차단기를 결합하여 모델 DoS 공격을 완벽히 방어한다.
