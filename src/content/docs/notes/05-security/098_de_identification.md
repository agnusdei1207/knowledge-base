## 미리 알고가기

- **직접 식별자**: 이름·주민등록번호처럼 그 자체로 개인을 알아보게 하는 정보
- **준식별자**: 나이·지역·직업처럼 다른 정보와 결합하면 개인을 알아볼 수 있는 정보
- **민감 속성**: 질병·소득처럼 노출 시 개인에게 큰 피해를 줄 수 있는 정보
- **가명처리**: 추가정보 없이는 특정 개인을 알아볼 수 없도록 개인정보를 처리하는 것
- **추가정보**: 가명정보를 원래 개인과 다시 연결할 수 있는 매핑표·복호화 키 등의 정보
- **익명처리**: 합리적으로 예상되는 수단으로도 개인을 알아볼 수 없도록 처리하는 것
- **마스킹**: 값의 일부를 가려 화면·문서의 불필요한 노출을 줄이는 기법
- **일반화**: 정확한 값을 연령대·지역 단위처럼 더 넓은 범주로 바꾸는 기법
- **억제**: 식별 위험이 큰 값이나 레코드를 삭제·비공개하는 기법
- **k-익명성**: 같은 준식별자 조합을 가진 사람이 최소 k명 존재하도록 만드는 기준
- **l-다양성**: 같은 준식별자 집단 안에 민감 속성이 최소 l개 존재하도록 만드는 기준
- **t-근접성**: 집단의 민감 속성 분포가 전체 분포와 크게 다르지 않도록 제한하는 기준
- **재식별 공격**: 처리된 데이터와 외부 정보를 결합해 개인을 다시 알아내는 공격
- **k·l·t 읽기와 표기**: “케이·엘·티”로 읽으며 각 수학 기호는 집단 크기·속성 다양성·분포 거리의 기준값을 나타냄

## Ⅰ. 개요

- **정의/개념**: 재식별 위험을 낮추는 정보 처리
- **배경/필요성**: 외부 결합에 따른 재식별 검증 필요

### 쉽게 이해하기 (학습용)

- 이름을 지운 뒤에도 다른 정보와 결합해 개인이 드러나는지를 확인함

## Ⅱ. 특징

- 가명정보는 개인정보 보호조치를 계속 적용한다.
- 익명정보는 합리적 수단으로 식별 불가능하다.
- 마스킹의 가명·익명 여부는 복원성으로 판단한다.
- 가명처리는 준비·검토·처리·관리 순으로 수행한다.

### 쉽게 이해하기 (학습용)

- 이름을 지우는 것만으로 끝내지 않고 다른 정보와 합쳤을 때도 누구인지 드러나지 않는지 확인하는 활동임

## Ⅲ. 아키텍처 및 구성요소

| 구성요소 | 설명 |
|:---|:---|
| 목적·법적 근거 | 분석·연구·통계·테스트 등 이용 목적과 허용 범위를 확정함 |
| 식별 위험 분석 | 직접 식별자·준식별자·민감 속성과 외부 결합 가능성을 찾음 |
| 처리 규칙 | 삭제·대체·일반화·억제·총계처리 등 위험 저감 기법을 적용함 |
| 추가정보·원본 통제 | 매핑표·키·원본을 분리하고 접근권한과 결합 절차를 제한함 |
| 적정성·유용성 검토 | 재식별 가능성과 분석 정확도를 함께 확인함 |

```text
                         [원본 데이터]
                               │
                  [식별자·준식별자·민감 속성 분류]
                               │
                         [처리 규칙 적용]
                   ┌───────────┴───────────┐
             [가명 데이터]             [익명 후보]
                   │                         │
        [통제된 이용 환경]          [재식별 가능성 검토]
                   │                         │
        [추가정보 분리 보관]          [익명 데이터 공개·이용]
```

- 가명은 이용 환경, 익명은 재식별성을 통제

### 쉽게 이해하기 (학습용)

- 가명화는 열쇠를 따로 보관하는 방식이고, 익명화는 현실적으로 다시 열 수 없게 만드는 방식임

## Ⅳ. 원리 및 절차 흐름도

```text
목적·범위 확정
↓
식별 위험 분석
↓
처리 기법 적용
↓
재식별·유용성 검토
↓
이용 환경 통제·지속 점검
```

| 절차 | 설명 |
|:---|:---|
| 목적·범위 확정 | 이용 목적·법적 근거·대상 데이터·제공 범위를 정함 |
| 식별 위험 분석 | 식별자와 외부 데이터 결합에 따른 재식별 가능성을 평가함 |
| 처리 기법 적용 | 목적에 필요한 정보만 남도록 삭제·대체·일반화·억제함 |
| 재식별·유용성 검토 | 공격 가능성과 분석 결과의 정확도를 함께 검증함 |
| 이용 환경 통제·지속 점검 | 접근·반출·결합 제한 후 재평가 |

> 요약: 목적별 재식별 위험·유용성을 검증함

### 쉽게 이해하기 (학습용)

- 이용 목적을 정하고 식별 위험을 낮춘 뒤 분석 가치와 이용 환경을 함께 검사함

## Ⅴ. 종류 및 비교

| 비교축 | 가명처리 | 익명처리 | 마스킹 |
|:---|:---|:---|:---|
| 핵심 특징 | 추가정보 없이는 개인을 알아볼 수 없도록 변환함 | 합리적 수단으로도 개인을 알아볼 수 없게 함 | 값 일부를 가려 노출 범위를 줄임 |
| 적용 기준 | 통계·연구 등 허용 목적에서 개인 단위 분석이 필요할 때 | 공개·공유 과정에서 개인 단위 식별이 필요 없을 때 | 화면·문서·테스트 환경에서 전체 값 노출이 불필요할 때 |
| 주요 위험 | 추가정보 유출·외부 데이터 결합으로 재식별될 수 있음 | 새 외부 데이터·기술로 익명성이 약해질 수 있음 | 원본 접근·복원 가능성을 놓치면 비식별로 오인할 수 있음 |

### 쉽게 이해하기 (학습용)

- 가명·익명·마스킹은 재연결 가능성과 이용 환경이 서로 다름

## Ⅵ. 실무 사례

- 의료 분석: 가명값·추가정보 분리
- 공공 공개: 지표와 결합 공격으로 검증

### 쉽게 이해하기 (학습용)

- 의료 분석은 환자별 분석이 필요하므로 가명정보와 연결 열쇠를 분리하고 접근·반출을 제한함
- 공개 데이터는 이론적 지표를 만족해도 다른 공개 자료와 합쳐 개인이 드러나는지 공격 관점에서 다시 확인함

## Ⅶ. 결론

- 재식별 위험·유용성·이용 환경을 반복 검증함

### 쉽게 이해하기 (학습용)

- 처리 기법 이름보다 “누가 어떤 외부 정보와 결합해 다시 알아볼 수 있는가”를 끝까지 확인하는 것이 핵심임
