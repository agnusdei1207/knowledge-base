## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **비식별 조치(De-identification / ISO/IEC 27559 & PIPA 제28조의2)**: 개인정보의 일부를 삭제하거나 대체(마스킹, 범주화, 암호화)함으로써 통계 작성, 과학적 연구, 공익적 기록 보존 등의 목적으로 활용할 때 특정 개인을 식별할 수 없도록 처리하는 기술적·관리적 보호 조치.
- **직접 식별자 vs 준식별자(Direct vs Quasi-Identifier)**:
  - **직접 식별자 (Direct Identifier)**: 주민등록번호, 성명, 전화번호, 이메일 등 단독으로 특정 개인을 고유하게 식별할 수 있는 항목.
  - **준식별자 (Quasi-Identifier / 간접 식별자)**: 나이, 성별, 거주지 우편번호, 직업 등 단독으로는 식별이 불가능하나 다른 공개 데이터와 결합(Linkage Attack)할 경우 특정 개인을 유일하게 지목할 수 있는 속성군.
- **모자이크 효과 결함(Mosaic Effect Linkage Defect)**: 이름 등 직접 식별자만 삭제하고 준식별자를 그대로 방치할 경우, 공격자가 외부의 공공 선거인 명부나 소셜 미디어 데이터와 결합하여 특정 개인의 민감 병력이나 금융 정보를 100% 재식별해 내는 연결 공격 취약점.

</details>

- 정의/개념: 식별 가능성을 낮춰 데이터를 활용하는 **비식별 처리**
- 배경/필요성: 빅데이터 분석, 인공지능 학습 및 이종 산업 간 데이터 결합 과정에서 성명 등 직접 식별자만 단순 마스킹할 경우, 성별·나이·우편번호 등 준식별자(Quasi-Identifier)가 외부 공공 데이터와 결합되어 특정 개인의 민감 정보가 100% 노출되는 모자이크 효과(Mosaic Effect Linkage Attack) 취약점이 발생함에 따라, ISO/IEC 27559 및 PIPA 데이터 3법(가명정보 제28조의2, 익명정보 제58조의2)에 기반하여 $k$-익명성, $l$-다양성, $t$-근접성, 차분 프라이버시 수학적 모델, 추가정보(매핑키) 망분리 격리 및 외부 전문가 적정성 평가를 결합하는 비식별 조치 아키텍처를 도입하여 **연결 재식별 공격 원천 차단, 데이터 유용성(Utility)과 프라이버시(Privacy) 간 파레토 최적화 및 합법적 빅데이터 활용 활성화**를 달성할 필요

#### 한줄 요약
- 직접 식별자를 제거하고 준식별자를 $k$-익명성/$l$-다양성으로 가공하여 재식별 연결 공격을 방어한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **가명정보 vs 익명정보 (Pseudonymized vs Anonymized Data)**:
  - **가명정보 (제28조의2)**: 추가정보(매핑키)를 복원해야만 개인을 알아볼 수 있는 정보로, 추가정보를 분리 보관하는 조건하에 동의 없이 통계/연구 목적으로 활용 가능하나 **여전히 법적 개인정보** 지위 유지.
  - **익명정보 (제58조의2)**: 시간·비용·기술 등 합리적으로 예상되는 모든 수단을 동원해도 더 이상 특정 개인을 알아볼 수 없는 정보로, **개인정보 보호법 적용이 전면 제외**되는 자유 데이터.

</details>

- **수학적 프라이버시 보호 모델의 엄밀성**: 군중 속에 숨기는 $k$-익명성, 동질성 공격을 방어하는 $l$-다양성, 전체 분포를 맞추는 $t$-근접성 기반 정량 통제
- **추가정보(매핑키)의 물리적 격리**: 가명처리 시 원본과의 복원 연결고리가 되는 매핑 테이블을 망분리된 독립 서버에 별도 보관하여 유출 위험 차단
- **유용성(Utility) vs 프라이버시(Privacy) 균형 최적화**: 데이터를 지나치게 뭉개면 분석 가치가 훼손되고 덜 뭉개면 재식별 위험이 증가하므로 서비스 목적에 맞춘 다차원 트레이드오프 튜닝

#### 한줄 요약
- 수학적 프라이버시 모델 적용, 추가정보 분리 보관, 가명/익명 법적 지위 구획, 유용성과 보안성의 균형을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **비식별 조치 4대 수학적 프라이버시 모델**:
  1. **$k$-익명성 ($k$-Anonymity)**: 동일한 준식별자 조합을 가진 레코드가 최소 $k$개 이상 존재하도록 보장.
  2. **$l$-다양성 ($l$-Diversity)**: 동일한 준식별자 동치류 내에 서로 다른 민감 속성이 최소 $l$개 이상 다양하게 분포.
  3. **$t$-근접성 ($t$-Closeness)**: 동치류 내 민감 속성 분포와 전체 데이터의 민감 속성 분포 간의 거리(EMD)를 $t$ 이하로 유지.
  4. **차분 프라이버시 (Differential Privacy)**: 개별 데이터의 유무에 따른 질의 결과의 통계적 노이즈를 $\epsilon$ 파라미터로 통제.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 식별자 분류 및 전처리 계층 (Identifier Classification Core) ]     │
│  ├─ 직접 식별자(성명, 주민번호) ➔ [ 암호화 삭제 / 해시 마스킹 100% 집행 ]│
│  └─ 준식별자(나이, 우편번호, 성별) ➔ 결합 모자이크 재식별 위험도 분석   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (준식별자 가공 파이프라인)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 수학적 프라이버시 변환 엔진 (Privacy Transformation Engine) ]      │
│  ├─ 일반화(Generalization): 28세 ➔ 20대, 서울시 강남구 역삼동 ➔ 서울시  │
│  ├─ 억제(Suppression): 이상치(희귀병, 극단적 고액 소득자) 레코드 도려내기│
│  ├─ [$k$-익명성] 동일 준식별자 집단 $k \ge 5$ 보장 (1인 핀셋 지목 차단) │
│  ├─ [$l$-다양성] 집단 내 질병 속성 $l \ge 3$ 보장 (동질성 공격 차단)   │
│  └─ [$t$-근접성] 집단 내 분포와 전체 분포 간의 거리 $t \le 0.15$ 제어  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (가공 완료 데이터 판정)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 법적 지위 분기 및 거버넌스 (Legal Status & Governance: PIPA) ]     │
│  ├─ [가명정보 (제28조의2)] ➔ 추가정보(매핑키) 망분리 격리 + 통계/연구용│
│  └─ [익명정보 (제58조의2)] ➔ 복원 불능 입증 ➔ [ PIPA 법 적용 전면 제외]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 식별자가 분류되어 수학적 변환 엔진에서 $k$-$l$-$t$ 기법으로 가공된 후, 가명정보와 익명정보로 법적 지위가 분기되어 안전하게 활용되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **직접 식별자 삭제기** | 성명, 전화번호, 주민번호 등 단독 식별 요소를 일방향 해시 또는 완전 삭제 | Pre-processing |
| **일반화/범주화 엔진** | 상세 수치(연령, 소득, 주소)를 상위 범주 구간으로 치환하여 식별성 축소 | Generalization |
| **$k$-익명성 보증기** | 준식별자 동치류(Equivalence Class)의 크기를 최소 $k$개 이상으로 묶어 군중화 | $k$-Anonymity |
| **$l$-다양성 보증기** | 동치류 내 민감 속성(병명 등)의 다양성을 $l$개 이상으로 확보하여 속성 추론 차단 | $l$-Diversity |
| **$t$-근접성 보증기** | 동치류 내 민감 속성 분포가 전체 데이터 분포와 $t$ 거리 이내로 유사하도록 제어 | $t$-Closeness |
| **추가정보 격리 저장소**| 가명 결합 키 및 암호화 솔트값을 운영망과 분리된 별도 서버에 격리 보관 | PIPA 제28조의4 |

#### 한줄 요약
- 직접 식별자 삭제기, 일반화 엔진, $k$-익명성, $l$-다양성, $t$-근접성 보증기, 추가정보 격리 저장소가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비식별 처리 5단계 전주기 프로세스 (가이드라인 표준)**:
  1. 사전 준비 (이용 목적 및 적법 근거 확정)
  2. 식별자 분류 (직접 식별자 vs 준식별자)
  3. 비식별 처리 실무 적용 (삭제, 마스킹, $k$-$l$-$t$ 변환)
  4. 적정성 검토 및 재식별 위험도 평가 (전문가 위원회 심사)
  5. 사후 관리 및 재식별 모니터링 (추가정보 분리 및 접근통제)

</details>

```text
1. [사전 준비 및 목적 확정] 암 질환 통계 분석 목적 확정 ➔ 원본 의료 데이터셋 10만 건 수집
            │
            ▼
2. [식별자 분류 및 전처리]
    ├─ 직접 식별자(환자명, 주민번호, 차트번호) ➔ SHA-256 일방향 해시 후 원본 컬럼 영구 DROP
    └─ 준식별자(나이, 우편번호, 성별) 및 민감 속성(진단 질병코드) 식별
            │
            ▼
3. [수학적 프라이버시 모델 적용]
    ├─ 나이(28세 ➔ 20대) 및 우편번호(13529 ➔ 135xx) 범주화 적용
    ├─ [$k$-익명성 ($k=5$)] 모든 준식별자 조합에 최소 5명 이상의 동일 그룹 생성
    └─ [$l$-다양성 ($l=3$)] 특정 그룹 5명 중 질병코드가 최소 3종류 이상 섞이도록 억제 조정
            │
            ▼
4. [적정성 평가 위원회 심사]
    ├─ 외부 프라이버시 전문가 패널이 외부 공공 데이터와의 모자이크 결합 재식별 시뮬레이션
    └─ [재식별 위험도 지수 $R \le 0.05$ 통과 및 통계 분석 유용성 손실률 10% 이내 승인]
            │
            ▼
5. [추가정보 분리 및 안전 활용]
    ├─ 복원용 매핑키를 물리적 망분리 HSM/서버에 암호화 격리 저장
    └─ [가명정보 연구망으로 배포 ➔ 연구 목적 활용 후 보유기간 만료 시 파기]
```

**동작 원리**

1. **사전 준비 및 목적 확정**
2. **식별자 분류 및 전처리**
3. **수학적 프라이버시 모델 적용**
4. **적정성 평가 위원회 심사**
5. **추가정보 분리 및 안전 활용**

#### 한줄 요약
- $k$ 값을 키울수록 재식별 위험은 내려가지만 데이터 해상도가 함께 깎이므로, 변환 강도는 분석 목적이 견딜 수 있는 유용성 손실선에서 결정된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 가공 수준별 3대 유형 비교**: 단순 화면 마스킹(Masking), 가명처리(Pseudonymization), 완전 익명처리(Anonymization)의 비교.

</details>

| 비교 항목 | 단순 시각 마스킹 (Masking) | 가명정보 (Pseudonymized) | 완전 익명정보 (Anonymized) |
|:---|:---|:---|:---|
| **복원 가능성** | **완전 복원 가능 (DB에 평문 존재)** | **추가정보(매핑키) 결합 시 복원 가능**| **영구적 복원 불가능 (불가역적)** |
| **법적 규제 지위** | **개인정보 보호법 100% 적용** | **개인정보 지위 유지 (안전조치 의무)**| **개인정보 보호법 적용 전면 제외** |
| **주요 적용 기법** | 화면 출력 시 `*`, `X` 마스킹 오버레이| **해시 치환, 토큰화, 범주화, $k$-익명성**| **극단적 일반화, 억제, 차분 프라이버시**|
| **이용 목적 제한** | 단순 화면 노출 방지 | **통계 작성, 과학적 연구, 공익적 기록**| **상업적 목적을 포함한 무제한 활용** |
| **핵심 보안 요구** | 접근권한 통제, 조회 로그 기록 | **추가정보(매핑키) 물리적 망분리 격리**| **재식별 가능성 지속적 사후 모니터링**|

#### 한줄 요약
- 마스킹은 단순 시각 가림, 가명정보는 매핑키 분리 보관 기반 연구용, 익명정보는 복원 불능으로 법 적용 제외이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **개인정보 보호법 제28조의2~5 (가명정보의 처리 등)**: 가명정보의 결합 제한, 안전성 확보조치(추가정보 분리), 특정 개인을 알아보기 위한 재식별 행위 금지 및 위반 시 전체 매출액 3% 이하 과징금 부과.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가명정보를 연구 목적으로 처리하면서 **복원용 매핑키(추가정보)를 동일 DB 서버에 함께 보관하여 해킹 시 원본이 100% 유출되는 결함** | **개인정보보호법 제28조의4** 준수, **추가정보를 물리적 망분리 서버에 격리 보관하고 접근권한을 별도 분리 통제** | 추가정보 유출 위험 0% 달성 및 가명정보의 법적 안전성 완벽 보장 |
| 이름만 마스킹한 데이터를 익명정보로 오인하여 외부에 무단 공개했다가 **공개 통계청 데이터와의 모자이크 결합으로 특정 개인 병력이 노출되는 사고** | **개인정보보호법 제58조의2** 기준, **$k$-익명성($k \ge 5$) 및 $l$-다양성($l \ge 3$) 수학적 검증과 외부 적정성 평가 심사 강제** | 모자이크 재식별 연결 공격 100% 사전 차단 및 안전한 데이터 개방 달성 |
| $k$-익명성을 극단적으로 높여 모든 데이터를 상위 범주로 뭉개버려 **머신러닝 모델 학습 시 데이터 왜곡으로 예측 정확도가 급락하는 유용성 훼손** | **ISO/IEC 27559** 준수, **재식별 위험도 지수($R$)와 데이터 손실률(Information Loss) 간의 파레토 최적화(Pareto Frontier) 튜닝** | 프라이버시 보호 기준 충족 및 AI 분석 모델 유용성 90% 이상 동시 확보 |

#### 한줄 요약
- 추가정보 분리 보관으로 유출을 막고, $k$-$l$-$t$ 모델로 모자이크 공격을 차단하며, 파레토 튜닝으로 유용성을 사수한다.

## Ⅶ. 결론

- 개인정보의 안전한 보호와 빅데이터·인공지능 혁신 활용 간의 균형을 제도적·수학적으로 뒷받침하는 **데이터 경제 시대 프라이버시 강화 컴퓨팅(ISO/IEC 27559 / PIPA 제28조의2·제58조의2)의 핵심 비식별 공학 체계**로 확고히 자리 잡았으며, 동형암호 기반 안전 결합 및 합성 데이터(Synthetic Data) 생성 기술로 진화하는 가운데, 실무 엔터프라이즈 데이터 레이크 및 결합 연구 플랫폼 구축 시에는 **직접 식별자 완전 삭제 및 $k$-익명성($k \ge 5$)·$l$-다양성($l \ge 3$) 수학적 변환 엔진 의무화, 복원용 매핑키의 물리적 망분리 HSM 격리 보관, 재식별 위험도 지수($R$)와 정보 손실률 간의 파레토 최적화 및 적정성 평가 위원회 2차 검증**을 결합하여 완벽한 비식별 조치 무결성을 완성

#### 한줄 요약
- $k$-$l$-$t$ 프라이버시 모델과 추가정보 분리 보관 및 적정성 평가를 통해 안전한 데이터 활용을 완성한다.
