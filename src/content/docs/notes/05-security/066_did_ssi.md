## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DID (분산 식별자)**: 내 개인정보를 구글이나 네이버 중앙 서버에 맡기지 않고, 블록체인 기술을 써서 내가 내 폰에 직접 들고 다니며 스스로 증명하는 차세대 신분증 체계다.
- **SSI (자기주권 신원)**: 내 신분증, 내 성적표 데이터를 IT 기업이 맘대로 못 쓰게 하고, 오직 나만이(Self-Sovereign) 데이터의 소유권과 통제권을 갖는 철학이다.
- **VC (검증 가능 자격증명)**: 대학교나 경찰청(발급자)이 위조 불가능하게 블록체인 전자서명을 딱 찍어서 내 스마트폰 지갑에 넣어주는 '디지털 졸업장/면허증' 파일이다.

</details>

- 정의: 중앙 인증 기관 없이 사용자가 직접 스마트폰 지갑(Wallet)에 자격 증명(VC)을 보관하고 제출하는 DID 및 SSI 분산 신원 체계이다.
- 배경: 카카오, 통신사 등 중앙 서버에 국민 개인정보가 쏠리면 대규모 유출 해킹에 취약하고, 기업이 내 동의 없이 데이터를 추적/가공하기 때문이다.

#### 한줄 요약

- 내 신분증 정보를 네이버 서버에 저장하지 말고, 내 폰 블록체인 지갑에 저장해서 내가 직접 통제하겠다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VP (검증 가능 프레젠테이션)**: 편의점에서 맥주 살 때 "민증 보여주세요" 하면 내 이름/주소 다 가리고 딱 '성인 여부'만 뽑아서 알바(검증자)한테 보여주는 제출용 데이터 덩어리다.
- **선택적 공개 (Selective Disclosure)**: 내 폰에 저장된 VC 데이터 중, 검증 기관이 요구하는 딱 필요한 속성만 쏙 빼서 보여주는 사생활 보호 기술이다.
- **DID 문서 (DID Document)**: 블록체인에 적혀있는 문서로, 발급자의 공개키와 검증 방법 등이 담겨있어 "이 증명서 진짜 맞다"고 확인시켜주는 용도다.

</details>

- **분산 신뢰 해소**: 블록체인 분산 원장에 저장된 DID 문서를 조회하여, 발급자의 공개키와 서명을 중앙 기관(CA) 없이 철저한 검증(해소)한다.
- **자격 소유와 검증 분리**: 자격 발급(VC)과 제출(VP) 단계를 완전히 분리하여, 사용자가 자기 데이터를 직접 소유하고 통제하는 SSI를 구현한다.
- **최소 정보 제공**: 영지식 증명(ZKP) 및 선택적 공개(Selective Disclosure) 기술을 적용하여 불필요한 민감 정보 노출을 원천 차단한다.

#### 한줄 요약

- 자격증명(VC) 발급과 제출(VP)을 쪼개고, 선택적 공개를 써서 내 정보 유출을 원천 차단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **발급자 (Issuer)**: 주체의 신원을 확인하고 블록체인 서명을 찍어 VC를 발급해 주는 기관(예: 경찰청, 대학교)이다.
- **검증자 (Verifier)**: 사용자가 낸 VP를 받고 "이거 진짜 면허증 맞나?" 블록체인에 물어보는 서비스 제공자(예: 렌터카, 편의점)다.
- **신뢰 등록부 (Trust Registry)**: 중앙 서버 대신 누구나 열람할 수 있게 DID 문서와 면허 정지(폐기) 목록을 기록해 둔 블록체인 장부다.

</details>

```text
[ DID / SSI 분산 신원 증명 아키텍처 ]

[ 1. 발급자 (Issuer) ] ── ("주민센터: 홍길동님, 여기 디지털 등본(VC) 발급해 드려요")
      │
      ▼
[ 2. 보유자 지갑 (Holder) ] ── ("홍길동: 오키, 내 폰 지갑에 안전하게 저장 완료!")
      │
      ▼
[ 3. 검증자 (Verifier) ] ── ("은행: 대출받으려면 등본 제출하세요")
      │
      ▼
[ 4. 선택적 VP 제출 ] ── ("홍길동: 전체 다 안 주고 '이름/주소'만 뽑아서 서명(VP) 제출함")
      │
      ▼
[ 5. 신뢰 등록부 (블록체인) ] ── ("은행: 블록체인 대조 결과 주민센터 서명 진짜 맞음! 통과!")
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **발급자 (Issuer)** | 주체의 자격을 확인하고 **위변조 불가능한 디지털 서명(VC)을 찍어서 발급함** | Issuer |
| **보유자 (Holder)** | 자기 스마트폰 지갑에 VC를 보관하고 **필요할 때만 속성을 쪼개서(VP) 제출함** | Holder |
| **검증자 (Verifier)** | 사용자가 제출한 VP를 받아 **블록체인 신뢰 장부를 뒤져서 진짜인지 철저한 검증함** | Verifier |
| **DID 문서 (Document)** | 발급자의 공개키, 검증 방법, 엔드포인트 등이 적혀있는 **블록체인 상의 증명서임** | Document |
| **신뢰 등록부 (Registry)** | 중앙 서버 대신 누구나 투명하게 **DID 문서와 자격 폐기 목록을 기록하는 블록체인망임** | Blockchain |

#### 한줄 요약

- 발급자가 서명해서 지갑에 꽂아주면, 보유자가 VP로 쪼개서 내고, 검증자는 블록체인으로 체크한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ DID 자격(VC) 발급 및 검증(VP) 통제 흐름 ]

┌──────────────────────────────┐
│ 1. [주체 자격 검증 및 DID 비밀키 기반 서명]
│ ("발급자(경찰청)가 면허증(VC)에 자기 프라이빗 키로 도장(서명)을 쾅 찍음")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [보유자 스마트폰 지갑(Wallet) 암호화 보관]
│ ("사용자가 VC를 받아 폰 내부의 안전한 보안 구역에 안전하게 보관아둠")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [동의 기반 선택적 공개 및 VP 생성]
│ ("렌터카 회사가 요구하면, 나이/면허번호만 쏙 빼서 VP로 조립 후 제출함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [신뢰 등록부(블록체인) 조회 및 폐기 상태 철저한 검증]
│ ("렌터카가 블록체인 뒤져서 경찰청 서명 맞는지, 면허 취소 안 됐는지 대조함")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 5. [암호학적 증명 완료 및 목적 적합성 판정]
    │ ("서명 무결성 확인 및 비즈니스 인가 조건 충족 시 최종 승인 완료!")
    └──────────────────────────────┘
```

### 동작 원리

1. 자격 심사 및 발급: 발급자가 주체 신원을 검증하고, 자기 DID 비밀키로 서명한 VC를 발급.
2. 지갑 보관: 보유자가 수신한 VC를 스마트폰 지갑(Wallet)에 암호화하여 보관.
3. 선택적 VP 생성: 검증자 요청 시, 보유자가 동의하에 최소 필요 속성만 골라 VP를 구성 및 서명하여 제출.
4. 블록체인 대조 검증: 검증자가 신뢰 등록부(블록체인)에서 발급자 DID 문서(공개키)와 폐기 상태(Status)를 조회.
5. 최종 판정: 제출된 VP의 암호학적 무결성과 목적 적합성(인가 조건)을 최종 평가.

#### 한줄 요약

- VC 발급 $\to$ 지갑 저장 $\to$ 속성만 쪼개서 VP 제출 $\to$ 블록체인(공개키/폐기목록) 철저한 검증 $\to$ 승인 순서다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 신원 인증 모델 | **중앙 신원 (Siloed Model)** | **연합 신원 (Federated/OAuth)** | **자기주권 신원 (DID / SSI)** |
|:---|:---|:---|:---|
| 핵심 특징 | **사이트 가입할 때마다 ID/PW 새로 파는 생수작업 반복** | **"카카오로 로그인" (편하긴 한데 카카오가 내 동선 다 봄)** | **내 폰에 있는 신분증 내가 꺼내서 직접 증명 (아무도 감시 못함)** |
| 핵심 특징 | 각 웹사이트 DB마다 내 개인정보가 **각자 파편화되어 저장됨** | 카카오/구글 같은 거대 IdP 기업이 **인증과 로그인 중계를 대행함** | 블록체인망 기반으로 **나(보유자) 자신이 직접 자격을 통제하고 제출함** |
| 치명적 한계 | 기업 DB 침해당하면 가입한 내 정보가 **그대로 유출 위험** | 편하지만 내가 어떤 사이트 썼는지 **빅테크 기업이 싹 다 추적(Tracking)함** | 개인이 폰 잃어버리거나 지갑 비번 까먹으면 **복구 절차가 미치도록 빡셈** |

#### 한줄 요약

- 매번 비번 치기(중앙), 빅테크 종속(연합)을 벗어나, 온전히 내 폰에서 내가 통제하는 게 **DID/SSI** 근거다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C DID Core 1.0**: 국제 웹 표준화 기구에서 "전 세계 DID는 무조건 이 포맷으로 만들어라" 하고 박아놓은 규격이다.
- **쌍별 DID (Pairwise DID)**: 네이버 접속할 땐 A라는 DID를 쓰고 쿠팡 접속할 땐 B라는 DID를 쓰게 해서, 네이버와 쿠팡이 뒤에서 "얘 홍길동이네" 하고 짬짜미(상관 추적)하는 걸 원천 차단하는 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 모바일 운전면허증 만들었더니 **다른 은행 앱에서는 호환 안 돼서 거부당함** | 발급 기관마다 식별자(DID) 체계와 자격증명(VC) 데이터 포맷을 지들 맘대로 짬 | 국제 표준인 **W3C DID Core 1.0 및 VC Data Model 2.0 전면 강제 적용** | 이기종 DID 지갑/앱 간의 100% 상호운용성(Interoperability) 보장 |
| 렌터카 빌렸더니 내 정보가 털려서 **맞춤형 대출 스팸 전화가 쏟아짐** | 검증 기관들이 사용자가 제출한 단일 DID 식별자를 공유해서 동선과 신원을 추적함 | 서비스마다 다른 식별자를 생성하는 **쌍별 DID(Pairwise) 및 선택적 공개 적용** | 기업 간 사용자 데이터 상관 추적(Correlation) 원천 원천 차단 및 프라이버시 보호 |
| 폰 잃어버렸는데 백업 안 해둬서 **평생 모은 자격증(VC) 싹 다 날아감** | SSI는 중앙 서버가 없으므로 개인키나 폰을 잃어버리면 복구 채널이 전무함 | 분산 키 관리 체계 기반의 **소셜 복구(Social Recovery) 및 안전한 키 복구 메커니즘 지원** | 개인키 상실 리스크 완화로 대국민 단위의 SSI 진입 장벽 해소 |

#### 한줄 요약

- **W3C 표준** 기반 통일하고, 기업이 뒤에서 못 캐게 **쌍별 DID** 쓰고, 폰 분실 대비 **키 복구** 챙겨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **분산 신원 신뢰 사슬 (Chain of Trust)**: 중앙 권위자 없이도 발급자 신원, DID 문서 공개키, VP 전자서명, 블록체인 폐기 목록이 톱니바퀴처럼 맞물려서 100% 신뢰를 만들어내는 검증 체계다.

</details>

- 빅테크의 개인정보 독점과 대규모 중앙 DB 유출을 종식시키기 위해, **W3C 표준** 대상 입각한 **발급자-보유자-검증자 3자 모델** 구축하고, 블록체인 기반의 **분산 신원 신뢰 사슬** 위에서 **VC 발급** 및 **선택적 VP 제시** 활용 연계하여 개인의 데이터 주권(SSI)을 복원하는 실무 기조를 확립함

#### 한줄 요약

- 빅테크 종속 버리고, **W3C 표준** 기반 **발급자-보유자-검증자** 3자 체계로 **SSI 주권** 찾아라.
