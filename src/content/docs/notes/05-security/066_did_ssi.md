## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **분산 식별자(Decentralized Identifier, DID)**: 중앙화된 중앙 등록기관 없이 사용자가 직접 생성•소유하고 검증 키와 제어 관계를 분산 저장소에서 확인하는 식별자 표준이다.
- **자기주권 신원(Self-Sovereign Identity, SSI)**: 개인이 자신의 디지털 신원에 대한 정보 소유권과 통제권을 직접 행사하는 차세대 신원증명 패러다임이다.
- **검증 가능 자격증명(Verifiable Credential, VC)**: 발급자가 사용자의 신원 속성 및 자격을 디지털 서명하여 발급한 위변조 불가능한 기계 판독형 자격 증명이다.

</details>

- 정의/개념: 사용자가 VC를 보관•제시하는 **DID•SSI**
- 배경/필요성: 중앙 신원은 **데이터 집중•서비스 간 추적** 유발

#### 한줄 요약

- 중앙기관 의존 없이 사용자 지갑에 서명된 자격(VC)을 보관하고 서비스 요청 시 필요 최소 정보만 제출하는 분산 신원 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DID 문서(DID Document)**: DID에 대응하는 공개키, 인증 메커니즘, 서비스 엔드포인트 정보가 포함된 JSON-LD 형식의 데이터 구조이다.
- **검증 가능 프레젠테이션(Verifiable Presentation, VP)**: 보유자가 하나 이상의 VC를 조합하고 자신의 DID 비밀키로 서명하여 검증자에게 제출하는 제출용 데이터 패키지이다.
- **선택적 공개(Selective Disclosure)**: 요청된 목적에 필요한 자격 속성만 선별 추출하거나 영지식 증명(ZKP)을 결합하여 영사/본문 전체 노출을 방지하는 기술이다.

</details>

- **DID 문서**를 통해 중앙 인증서 기관(CA) 없이 식별자의 공개키 및 검증 신뢰 관계를 해소(Resolution)한다.
- **VC** 발급과 **VP** 생성/제시 단계를 분리하여 개인정보 소유 및 암호학적 위변조 검증을 동시 보장한다.
- **선택적 공개** 및 영지식 증명 적용으로 최소 수집 원칙을 구현하고 프라이버시 침해를 차단한다.

#### 한줄 요약

- 발급 기관의 디지털 서명이 결합된 VC를 사용자가 직접 보관하고 VP 형태로 최소 속성만 선별 제공하여 검증받는다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **발급자(Issuer)**: 주체의 자격을 확인하고 암호화 서명을 부여하여 VC를 발급하는 신뢰할 수 있는 기관이다.
- **보유자(Holder)**: 발급된 VC를 단말 지갑(Wallet)에 암호화 보관하고, 서비스 요청 시 VP를 생성해 제출하는 주체이다.
- **검증자(Verifier)**: 제출된 VP의 디지털 서명, VC 유효성, 상태 정보 및 발급자 신뢰를 판정하는 서비스 주체이다.
- **신뢰 등록부(Verifiable Data Registry / Trust Registry)**: DID 문서, 발급자 공개키, VC 폐기 목록(Status List)을 분산 보관하는 블록체인 또는 DLT 기반 저장소이다.
- **상태 정보(Status List / Revocation Status)**: VC의 효력 정지, 폐기 및 만료 상태 정보를 비대칭 검증할 수 있도록 제공하는 메타데이터이다.

</details>

```text
[DID·DID 문서]---[발급자]---[보유자·지갑]---[검증자]
        |              |                         |
        +------[신뢰·상태·키 관리]-------------+
```

선의 의미: 신뢰 등록부(블록체인) 중심의 DID 문서 해소 체계 위에서 발급자, 보유자, 검증자가 상호작용하는 SSI 3자 모델 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| DID·DID 문서 | **DID 문서** 기반 식별자 해소, 공개키•인증 수단 제공 |
| 발급자 | **발급자**의 신원 속성 검증, 디지털 서명 및 VC 발급 처리 |
| 보유자·지갑 | **보유자**의 개인키/VC 암호화 보관, 동의 기반 최소 VP 생성 및 제출 |
| 검증자 | **검증자**의 VP 서명 검증, VC 폐기 상태 및 신뢰 등록부 대조 판정 |
| 신뢰·상태·키 관리 | **신뢰 등록부** 및 **상태 정보**를 통한 공개키 해소, 폐기 검증 및 키 회전 처리 |

#### 한줄 요약

- 발급자가 서명한 VC를 보유자가 지갑에 관리하고, 검증자는 신뢰 등록부의 DID 문서로 서명과 폐기 상태를 검증한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **암호학적 증명(Cryptographic Proof)**: VC 및 VP에 부착되어 데이터 무결성, 발급자 신원, 보유자 소유권을 입증하는 서명 데이터이다.
- **목적 적합성 판정(Purpose-Fit Evaluation)**: 암호적 서명이 유효하더라도 현재 서비스 제출 목적에 맞는지 검증자가 정책적으로 확인하는 과정이다.
- **주체•자격 주장 검증(Subject & Claim Verification)**: 발급자가 사용자 신원과 자격 주장 내용의 타당성을 심사하는 단계이다.
- **DID 키 기반 VC 서명(DID Key-based VC Signing)**: 발급자가 자신의 DID 비밀키로 주장 내용과 유효기간을 암호 서명하여 VC를 생성하는 단계이다.
- **동의•선택 공개 VP 생성(Consented Selective Disclosure VP Generation)**: 보유자가 검증자 요구 항목에 맞게 필요한 속성만 추출하여 VP를 서명 구성하는 단계이다.
- **발급자•상태•키 검증(Issuer, Status & Key Verification)**: 검증자가 신뢰 등록부에서 발급자 DID 문서의 공개키와 VC 폐기 목록을 조회·검증하는 단계이다.
- **증명•목적 적합성 판정(Proof & Purpose-Fit Determination)**: 전자서명 무결성과 비즈니스 인가 조건 충족 여부를 최종 평가하는 단계이다.

</details>


### 동작 원리

1. **주체•자격 주장 검증**: 사용자 신원•자격 심사
2. **DID 키 기반 VC 서명**: 발급자 서명 VC 생성•전달
3. **동의•선택 공개 VP 생성**: 최소 속성 추출•보유자 서명
4. **발급자•상태•키 검증**: 공개키•폐기 상태 대조
5. **증명•목적 적합성 판정**: 서명•인가 조건 최종 평가

#### 한줄 요약

- 자격 발급부터 선택적 VP 제시, 신뢰 등록부 기반 전자서명 및 폐기 상태 검증으로 신원 인증을 완결한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 신원(Centralized Identity)**: 서비스 제공 기관이 사용자 식별 정보와 자격 인증을 모두 독점 보관·통제하는 전통적 모델이다.
- **연합 신원(Federated Identity)**: OAuth, SAML, OIDC를 통해 IdP(Identity Provider)가 타 서비스 로그인 인증을 대행 중계하는 모델이다.

</details>

| 디지털 신원 모델 | DID•SSI | 중앙 신원 모델 | 연합 신원 (IdP) |
|:---|:---|:---|:---|
| 적용 기준 | 개인정보 주권 보장 및 이기종 간 정보 증명 | 단일 기관 내부 서비스 계정 관리 | SSO 및 타사 로그인 통합 연동 |
| 핵심 특징 | **DID**•**SSI** 기반 보유자 직접 자격 관리 | **중앙 신원**의 중앙 DB 직접 통제 | IdP 중심 인증 중계 및 토큰 전달 |
| 한계 | 개인키 분실 복구 및 폐기 검증 구현 난이도 | 데이터 집중 유출 및 싱글 포인트 장애 | IdP 추적(Tracking) 및 서비스 의존성 |

#### 한줄 요약

- 중앙 DB 저장 및 IdP 추적 문제를 해결하기 위해 보유자 중심의 자기주권 신원(DID/SSI) 모델로 진화한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C DID Core 1.0**: DID 식별자 구조, DID 문서 데이터 모델 및 CRUD 동작 표준 규격이다.
- **W3C VC Data Model 2.0**: VC 및 VP의 표준 JSON-LD 표현, 서명 구조 및 검증 표준 모델이다.
- **쌍별 DID(Pairwise DID)**: 검증자 서비스마다 서로 다른 DID를 동적 생성하여 서비스 간 사용자 상관 추적(Correlation)을 차단하는 기법이다.
- **키 복구(Key Recovery)**: 단말 분실 시 시드 문구(Seed Phrase), 소셜 복구, 또는 분산 키 복구(DKMS)를 통해 통제권을 안전하게 되찾는 메커니즘이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 이기종 플랫폼 간 연동 표준 미비 | **W3C DID Core 1.0** 지침 적용 | 식별자 해소 및 공개키 매핑 상호운용성 확보 |
| VC/VP 표준 파편화 | **W3C VC Data Model 2.0** 적용 | 발급-제시-검증 파이프라인의 데이터 호환성 보장 |
| 사용자 추적 및 단말 분실 | **쌍별 DID**, **선택적 공개**, **키 복구** 메커니즘 적용 | 프라이버시 추적 방지 및 개인키 상실 위험 완화 |

#### 한줄 요약

- W3C 국제 표준 규격을 준수하고, 상관 추적 방지를 위한 Pairwise DID 및 키 복구 메커니즘을 반영한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **분산 신원 신뢰 사슬(Decentralized Identity Chain of Trust)**: 발급자 신원, DID 문서 공개키, VC/VP 전자서명, 폐기 상태 목록이 유기적으로 결합되어 완성되는 신뢰 검증 체계이다.

</details>

- **분산 신원 신뢰 사슬**을 형성하여 조직 간 검증은 **DID**•**SSI**, 사내 시스템은 **중앙 신원**, 소셜 로그인은 **연합 신원**을 상호보완 적용한다.

#### 한줄 요약

- 조직 간 증명은 **DID•SSI**, 사내는 **중앙 신원** 적용
