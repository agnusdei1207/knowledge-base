## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DID(Decentralized Identifier, 분산 식별자 / W3C 표준)**: 중앙화된 신원 등록 기관(CA)이나 빅테크 플랫폼에 종속되지 않고, 블록체인 등 분산 원장 기술(DLT)을 활용하여 사용자가 직접 생성·소유·제어할 수 있는 암호학적으로 검증 가능한 전역 고유 URI 식별자.
- **SSI(Self-Sovereign Identity, 자기주권 신원)**: 사용자가 자신의 개인정보와 디지털 신원에 대한 완전한 주권과 통제권을 보유하며, 제3자 서비스 이용 시 불필요한 개인정보 노출 없이 필요한 속성만 선택적으로 증명할 수 있는 신원 패러다임.

</details>

- 정의/개념: W3C **DID** Core 1.0 및 VC Data Model에 기반하여 발급자(Issuer) $\rightarrow$ 보유자(Holder) $\rightarrow$ 검증자(Verifier) 로 이어지는 신뢰 삼각관계(Trust Triangle)를 구축하고, 분산 원장(Verifiable Data Registry)을 통한 공개키 해소(Resolution)와 선택적 공개(Selective Disclosure) 를 집행하는 탈중앙화 신원 인증 아키텍처
- 배경/필요성: 전통적인 중앙 집중형 인증 및 플랫폼 빅테크 기반의 연합 신원(IdP/SSO) 체계는 특정 서버 침해 시 대규모 개인정보 유출, 빅테크 기업에 의한 사용자 활동 로그 및 행태 추적(Tracking), 사용자의 데이터 주권 상실이라는 구조적 한계를 노출함에 따라, 블록체인 등 분산 원장 기술(DLT)과 암호학적 디지털 서명을 기반으로 중앙 중개자 없이 사용자 본인이 신원 데이터를 직접 소유·통제하는 W3C DID Core 1.0 및 자기주권 신원(**SSI**: Self-Sovereign Identity) 아키텍처를 도입하여 개인정보 자기결정권(Data Sovereignty) 확보, 선택적 공개(Selective Disclosure) 및 영지식 증명(ZKP)을 통한 프라이버시 극대화, 분산 신뢰 삼각관계(Issuer-Holder-Verifier) 기반의 안전한 검증 체계를 달성할 필요

#### 한줄 요약
- SSI는 신뢰를 없앤 것이 아니라 검증 시점의 기관 질의를 발급 시점의 서명으로 앞당겨, 검증자가 발급자와 접촉하지 않고도 자격을 확인할 수 있게 만든 구조다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VC(Verifiable Credential) vs VP(Verifiable Presentation)**:
  - **VC (검증 가능 자격증명)**: 발급자(경찰청, 대학 등)가 사용자의 자격(운전면허, 졸업증명)에 대해 개인키로 전자서명하여 발급한 위변조 불가능한 원본 데이터셋.
  - **VP (검증 가능 프레젠테이션)**: 보유자가 검증자에게 제출하기 위해 하나 이상의 VC에서 필요한 속성(예: 생년월일 전체 대신 '성인 여부'만 추출)을 결합하고 자신의 개인키로 서명한 제출용 데이터.

</details>

- 중앙 인증 기관(CA) 배제: 분산 원장(블록체인)에 등록된 DID 문서를 통해 발급자의 공개키와 서명 유효성을 수학적으로 직접 해소(Resolution)
- 프라이버시 보존형 선택적 공개 (Selective Disclosure & ZKP): 영지식 증명(Zero-Knowledge Proof)을 적용하여 원본 데이터의 노출 없이 자격 요건 충족 여부만 증명
- 상관 추적 방지 (Pairwise Pseudonymous DID): 서비스별로 서로 다른 DID를 생성하여 서비스 제공자 간의 사용자 행태 교차 추적(Correlation) 원천 차단

#### 한줄 요약
- 프라이버시와 탈중앙 통제를 얻은 대가로 키 분실에 대비할 중앙 복구 창구가 사라져, 신원 복구의 책임까지 사용자에게 함께 넘어간다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DID 신뢰 삼각관계(Trust Triangle) 4대 구성요소**:
  1. **Issuer (발급자)**: 자격을 검증하고 서명된 VC를 발행하는 신뢰 기관.
  2. **Holder (보유자)**: 스마트폰 보안 지갑(Edge Wallet)에 VC를 저장하고 통제하는 사용자.
  3. **Verifier (검증자)**: 사용자가 제출한 VP를 검증하여 비즈니스 인가를 제공하는 서비스.
  4. **Verifiable Data Registry (신뢰 등록부)**: DID 문서, 암호화 키, 자격 폐기 목록(Revocation List)을 보관하는 분산 원장.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 신뢰 등록부 (Verifiable Data Registry: 블록체인 / 분산 원장) ]      │
│  ├─ 발급자 DID 문서 (`did:example:issuer123` ➔ 공개키 등록)             │
│  └─ 자격증명 폐기 레지스트리 (Revocation Registry / StatusList2021)     │
└──────────────▲───────────────────────────────────────────▲──────────────┘
                │ (1. DID 문서 등록)                        │ (4. 공개키/폐기상태 조회)
┌──────────────┴──────────────────────────┐  (3. VP 제출)  ┌──────────────┴──────────────┐
│ [ 2. 발급자 (Issuer: 기관) ]            │ ─────────────▶ │ [ 4. 검증자 (Verifier: 서비스) ]
│  └─ 주체 검증 ➔ 서명된 VC 발급           │                │  └─ 서명 검증 및 자격 인가   │
└──────────────┬──────────────────────────┘                └─────────────────────────────┘
                │ (2. VC 발급 전달)                                │
                ▼                                                  │
┌─────────────────────────────────────────────────────────────────┴───────┐
│ [ 3. 보유자 (Holder / Edge Wallet: 사용자 스마트폰 단말) ]               │
│  ├─ 하드웨어 보안 영역(TPM/Secure Enclave)에 개인키 격리 보관           │
│  └─ [ 필요 속성만 선별 ➔ 홀더 개인키 서명 ➔ Verifiable Presentation 생성]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 발급자가 DID 문서를 분산 원장에 등록하고 VC를 발급하면, 보유자가 지갑에서 VP를 생성해 검증자에게 제출하고, 검증자는 분산 원장 조회로 무결성을 검증하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| 발급자 (Issuer) | 주체의 자격 요건을 실사하고 개인키로 전자서명한 **VC**(W3C JSON-LD) 발행 | Credential Issuer|
| 보유자 (Holder/Wallet)| 모바일 보안 영역에 **VC**를 저장하고, 동의 기반으로 필요한 속성만 결합해 **VP** 제출 | Identity Wallet |
| 검증자 (Verifier) | 수신된 VP의 서명 무결성, 발급자 신원, 폐기 여부를 분산 원장을 통해 검증 | Relying Party |
| 신뢰 등록부 (Registry) | 블록체인/분산 원장 기반으로 DID Document, 공개키, 폐기 목록을 무결하게 분산 보관 | Trust Substrate |
| DID Document (DID 문서)| 특정 DID에 대응하는 공개키(Public Key), 인증 메커니즘, 서비스 엔드포인트 명세 | W3C Standard |

#### 한줄 요약
- 분산 원장에는 개인 데이터가 아니라 공개키와 폐기 상태만 올라가므로, 원장은 신원 저장소가 아니라 서명을 검증할 근거만 제공하는 최소한의 신뢰 기반으로 설계된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DID 자격증명 발급 및 검증 5단계 흐름**:
  1. 발급자가 신뢰 등록부에 자신의 DID Document 등록
  2. 보유자 신원 확인 후 서명된 VC 발급 및 지갑 저장
  3. 검증자가 챌린지와 함께 특정 자격 증명 제출(VP) 요청
  4. 보유자가 필요한 속성만 선택 추출하여 VP 생성 및 서명 제출
  5. 검증자가 분산 원장을 통해 발급자 서명 및 폐기 상태 대조 후 인가

</details>

```text
1. [DID 문서 등록] 발급자(경찰청)가 블록체인에 자신의 공개키가 포함된 DID Document 등록
            │
            ▼
2. [VC 발급 및 지갑 저장] 사용자가 신원 확인 후 경찰청으로부터 서명된 운전면허 VC를 발급받아 모바일 지갑에 보관
            │
            ▼
3. [검증 요청 (Proof Request)] 렌터카 웹사이트(검증자)가 일회용 난수(Nonce)와 함께 "운전면허 유효성 + 21세 이상" 증명 요구
            │
            ▼
4. [선택적 VP 조립 및 제출]
    ├─ 보유자 지갑이 VC에서 주민번호/주소를 마스킹하고 `[운전면허 1종, 만 21세 이상=True]` 속성만 추출
    └─ 보유자의 개인키로 서명하여 Verifiable Presentation(VP) 생성 후 전송
            │
            ▼
5. [분산 해소 및 암호학적 검증]
    ├─ 검증자가 블록체인에서 경찰청 DID 문서를 해소(Resolve)하여 VC 서명 검증
    ├─ 블록체인 폐기 레지스트리를 조회하여 면허 정지 여부 확인
    └─ [전 항목 통과 ➔ 렌터카 대여 서비스 최종 인가 완료]
```

1. 직접 서명 검증: 중앙 CA 서버에 실시간 질의하지 않고 블록체인 상의 공개키로 수학적 서명 무결성 증명
2. 정보 최소화 원칙(Data Minimization): 원본 데이터 전체를 넘기지 않고 조건 충족 여부(True/False)만 제출
3. 발급자와 검증자 간 결탁 차단: 발급자는 사용자가 언제 누구에게 VP를 제출했는지 추적 불가능
4. 리플레이 공격 봉쇄: 검증자가 발행한 고유 1회용 난수(Nonce)를 VP 서명에 포함하여 재전송 공격 방어
5. 실시간 자격 폐기 검증: 암호학적 누산기(Cryptographic Accumulator) 또는 상태 목록을 통해 폐기 상태 확인

#### 한줄 요약
- 검증자가 발급자에게 묻지 않고도 자격을 확인하는 대신 폐기 상태만은 원장을 조회해야 하므로, 실시간 조회가 필요한 지점이 신원 확인 전체에서 폐기 여부 하나로 좁혀진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **디지털 신원 모델 3대 패러다임 비교**: 중앙 집중형(Siloed), 연합형(Federated SSO), 자기주권 신원(DID/SSI)의 비교.

</details>

| 비교 항목 | 중앙 집중형 신원 (Siloed) | 연합형 신원 (Federated / OAuth) | 자기주권 신원 (DID / SSI) |
|:---|:---|:---|:---|
| 신원 데이터 저장소 | 각 개별 웹사이트 데이터베이스 | 빅테크 IdP (Google, Kakao 등) | 사용자 개인 단말 지갑 (Edge Wallet) |
| 사용자 데이터 주권 | 기업이 소유 및 통제 | 빅테크 플랫폼에 종속 | 사용자가 100% 완전 소유 및 통제 |
| 개인정보 유출 위험 | 웹사이트 침해 시 평문/해시 유출 | IdP 침해 시 전 서비스 연쇄 침해 | 중앙 DB 부재로 대규모 유출 원천 불가 |
| 사용자 프라이버시 | 파편화된 식별자 사용 | 빅테크가 사용자의 로그인 동선 추적 | 선택적 공개/영지식 증명으로 추적 차단 |
| 신원 검증 신뢰 기반| 개별 사이트 자체 인증 | IdP 중앙 인증 서버 실시간 질의 | 분산 원장(블록체인) 기반 수학적 검증 |

#### 한줄 요약
- 세 모델의 차이는 편의성이 아니라 신원 데이터가 어디에 쌓이느냐이며, 쌓이는 지점이 곧 대규모 유출과 행태 추적이 발생하는 지점이 된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **소셜 복구(Social Recovery)**: 단말기 분실 시 중앙 서버 없이도 사용자가 사전에 지정한 N명의 신뢰할 수 있는 보호자(Guardians) 중 M명의 다중 서명을 모아 분산 개인키를 안전하게 복원하는 암호학적 키 복구 메커니즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 기관별 상이한 데이터 스키마로 인해 모바일 운전면허증 등 발급된 VC가 타 서비스에서 상호 호환되지 않는 파편화 | W3C DID Core 1.0 및 W3C Verifiable Credentials Data Model 2.0 국제 표준 규격 전면 채택 | 이기종 지갑 및 검증기 간의 100% 글로벌 상호운용성(Interoperability) 확보 |
| 여러 검증자(Verifier)가 단일 DID를 교차 대조하여 사용자의 서비스 이용 행태와 위치를 역추적하는 프라이버시 침해 | 서비스마다 독립적인 식별자를 동적 생성하는 쌍별 DID(Pairwise DID) 및 영지식 증명(ZKP) 강제 | 기관 간 결탁을 통한 사용자 데이터 상관 추적(Correlation) 100% 원천 차단 |
| 스마트폰 분실 및 하드웨어 파손 시 중앙 복구 경로가 없어 보유자의 모든 자격증명(VC)이 영구 유실되는 결함 | Shamir 비밀 분할 기반의 **소셜 복구**(Social Recovery) 및 보안 클라우드 백업 프레임워크 지원 | 단일 기기 분실에 따른 계정 잠금 해소 및 엔터프라이즈급 신원 복원력 달성 |

#### 한줄 요약
- 표준과 쌍별 DID로 통제권을 사용자에게 모을수록 지갑 하나에 걸린 위험도 커지므로, SSI 도입의 성패는 암호 기술이 아니라 키 복구 설계에서 갈린다.

## Ⅶ. 결론

- 빅테크 기업과 중앙 정부에 집중되었던 신원 권력을 개인에게 환원하고 디지털 환경에서 데이터 주권을 실현하는 차세대 탈중앙화 디지털 신원(W3C DID / SSI) 및 신뢰 프레임워크의 핵심 표준으로 확고히 자리 잡았으며, 모바일 신분증(모바일 운전면허증, 공무원증 등) 및 웹3(Web3) 생태계로 전면 확산되는 가운데, 실무 DID/SSI 시스템 구축 시에는 W3C VC Data Model 2.0 표준 규격 준수, 사용자 행태 추적을 원천 차단하는 쌍별 DID(Pairwise DID) 및 영지식 증명(ZKP) 기반 선택적 공개 구현, 단말 분실에 대비한 Shamir 비밀 분할 기반 소셜 복구(Social Recovery) 체계 마련, 블록체인 분산 레지스트리를 통한 실시간 자격 폐기(Revocation) 검증을 결합하여 완벽한 자기주권 신원 생태계를 완성

#### 한줄 요약
- SSI는 신원 관리 비용을 기관에서 사용자에게 옮긴 선택이므로, 프라이버시 이득이 개인의 키 관리 부담을 넘어서는 영역부터 우선 적용해야 한다.
