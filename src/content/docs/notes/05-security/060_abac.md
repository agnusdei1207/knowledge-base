## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **속성 기반 접근 제어(Attribute-Based Access Control, ABAC)**: 주체•객체•행위•환경 속성을 정책으로 평가하는 접근 제어 모델이다.
- **역할 기반 접근 제어(Role-Based Access Control, RBAC)**: 권한을 역할에 묶어 사용자에게 배정하는 접근 제어 모델이다.

</details>

- 정의/개념: **ABAC**는 요청 시점의 주체•객체•행위•환경 속성을 정책으로 평가한다.
- 배경/필요성: **RBAC**만으로는 시간•기기•데이터 등급 같은 동적 맥락을 세밀하게 반영하기 어렵다.

#### 한줄 요약

- 직무 하나만 보지 않고 누가 어떤 문서를 어떤 기기와 시간에 무슨 행위로 여는지를 함께 따진다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **주체 속성**: 요청자의 신원•조직•직무•보안 상태를 나타내는 판단값이다.
- **객체 속성**: 대상 자원의 소유자•등급•유형을 나타내는 판단값이다.
- **행위 속성**: 읽기•쓰기•승인처럼 요청한 동작을 나타내는 판단값이다.
- **환경 속성**: 요청 시점의 시간•위치•기기 상태를 나타내는 판단값이다.
- **정책 정보점(Policy Information Point, PIP)**: 정책 평가에 필요한 신뢰 속성을 제공하는 구성요소이다.
- **정책 결정점(Policy Decision Point, PDP)**: 속성과 정책을 평가해 허용•거부를 결정하는 구성요소이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: 정책 결정 결과를 실제 요청에 집행하는 구성요소이다.
- **속성 신선도**: 속성값이 요청 시점의 실제 상태를 정확히 반영하는 정도이다.

</details>

- **주체 속성**•**객체 속성**•**행위 속성**•**환경 속성**을 조합한다.
- **PIP**가 속성을 제공하고 **PDP**가 결정하며 **PEP**가 집행한다.
- **속성 신선도**와 신뢰성이 요청 시점 판정의 정확도를 좌우한다.

#### 한줄 요약

- 조건을 세밀하게 만들 수 있지만 값이 오래되거나 틀리면 정당한 사용자를 막거나 공격자를 허용할 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **속성 권위자**: 정책 평가에 사용하는 신뢰 속성을 생성•갱신하는 주체이다.
- **정책 저장소**: 접근 규칙과 정책 조합 방식을 보관하는 저장소이다.

</details>

```text
ABAC 정책 구조
├─ 정책 집행점 PEP: 정책 결정 집행
├─ 정책 결정점 PDP: 속성•정책 평가
├─ 정책 저장소: 규칙•충돌 기준 관리
├─ 속성 정보점 PIP: 신뢰 속성 조회
└─ 속성 권위자: 신뢰 속성 생성•갱신
```

| 구성요소 | 책임 |
|:---|:---|
| 정책 집행점 PEP | **PEP**의 요청 전달•정책 결정 집행 |
| 정책 결정점 PDP | **PDP**의 속성•정책 평가 |
| 정책 저장소 | **정책 저장소**의 규칙•충돌 기준 관리 |
| 속성 정보점 PIP | **PIP**의 신뢰 속성 조회 |
| 속성 권위자 | **속성 권위자**의 신뢰 속성 생성•갱신 |

#### 한줄 요약

- 집행점이 질문하면 결정점이 정책과 신뢰 속성을 조회해 답하고 집행점이 그 답대로 자원 접근을 허용하거나 거부한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **생존 시간(Time to Live, TTL)**: 조회한 속성값을 다시 확인하기 전까지의 유효 시간이다.
- **기본 거부**: 평가 오류를 포함해 정책이 명시적으로 허용하지 않은 요청을 거부하는 원칙이다.
- **요청 속성•맥락 추출**: 접근 요청에서 주체•객체•행위•환경 판단값을 구성하는 단계이다.
- **적용 정책•충돌 규칙 선택**: 대상 자원에 적용할 규칙과 상충 결정 조합 방식을 고르는 단계이다.
- **권위자•TTL•무결성 검증**: 속성의 출처•신선도•변조 여부를 확인하는 단계이다.
- **정책 평가•기본 거부**: 속성 조합을 계산하고 명시적으로 허용되지 않은 요청을 거부하는 단계이다.
- **결정 집행•감사 기록**: 허용된 동작만 자원에 전달하고 판정 근거를 남기는 단계이다.

</details>

```text
접근 요청
    |
    v
1. 요청 속성•맥락 추출
    |
    v
2. 적용 정책•충돌 규칙 선택
    |
    v
3. 권위자•TTL•무결성 검증
    |
    v
4. 정책 평가•기본 거부
    |
    +-- 오류•불일치 -- 거부
    |
    +-- 명시적 허용 -- 5. 결정 집행•감사 기록
                               |
                               v
                          보호 자원 접근
```

### 동작 원리

1. **요청 속성•맥락 추출**: 주체•객체•행위•환경 판단값으로 요청 속성•맥락을 추출한다.
2. **적용 정책•충돌 규칙 선택**: 요청 대상에 적용할 정책•충돌 규칙을 선택한다.
3. **권위자•TTL•무결성 검증**: 최신의 신뢰 가능한 속성인지 권위자•TTL•무결성을 검증한다.
4. **정책 평가•기본 거부**: 속성 조합을 계산하고 정책 평가•기본 거부를 적용한다.
5. **결정 집행•감사 기록**: 허용된 동작만 전달하고 결정 집행•감사 기록으로 근거를 보존한다.


#### 한줄 요약

- 실제 요청마다 필요한 속성을 신뢰 출처에서 가져와 정책과 비교하고 허용된 행위만 보호 자원에 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **혼합 모델**: RBAC 역할 권한에 ABAC 속성 조건을 추가하는 접근 제어 모델이다.

</details>

| 접근 제어 모델 | ABAC | RBAC | 혼합 모델 |
|:---|:---|:---|:---|
| 적용 기준 | 맥락•데이터별 세밀 통제 | 안정된 직무 권한 | 기본 역할의 조건 강화 |
| 핵심 특징 | **ABAC**의 속성 조합 동적 판정 | **RBAC**의 역할 기반 권한 배정 | **혼합 모델**의 역할+속성 조건 |
| 한계 | 속성•정책 복잡성 | 역할•예외 과다 | 규칙 충돌•책임 중복 |

#### 한줄 요약

- RBAC는 직무 중심, ABAC는 요청 맥락 중심이며 혼합형은 직무 권한에 필요한 동적 조건만 덧붙인다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-162**: 속성 기반 접근 제어의 정의와 설계 고려사항을 제시하는 미국 국립표준기술연구소 지침이다.
- **OASIS XACML 3.0 Errata 01**: 속성 기반 정책 언어와 처리 모델을 정의하는 표준판이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 속성 정의•관리 책임이 다르면 같은 요청의 판정 불일치 | **NIST SP 800-162** 적용 | 주체•객체•환경의 정의 정렬 |
| 제품별 정책 처리 방식이 달라 집행 결과 불일치 | **OASIS XACML 3.0 Errata 01** 적용 | PEP•PDP•PIP의 인터페이스 통일 |
| 오래된 속성•정책 충돌로 비인가 요청 허용 | **속성 권위자**•**TTL**과 **기본 거부** 적용 | 비인가 허용과 판정 불일치 방지 |

#### 한줄 요약

- 사용자의 직무 권한이 있어도 기기 관리 상태와 문서 등급 속성을 함께 평가해 비관리 기기에는 기밀 문서 다운로드를 허용하지 않는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **신뢰 속성**: 권위 있는 출처에서 최신성과 무결성이 검증된 정책 판단값이다.
- **설명 가능성**: 어떤 속성과 정책이 접근 결정에 영향을 주었는지 추적하는 성질이다.

</details>

- **신뢰 속성**과 **설명 가능성**을 확보하며 안정된 직무는 **RBAC**, 동적 맥락은 **ABAC**, 역할에 일부 조건만 필요하면 **혼합 모델**을 선택한다.

#### 한줄 요약

- ABAC의 핵심은 조건의 개수가 아니라 최신의 믿을 수 있는 속성으로 일관되게 결정하고 그 이유를 설명하는 것이다.
