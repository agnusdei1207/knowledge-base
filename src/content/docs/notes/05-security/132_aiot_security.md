## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **IoT(Internet of Things)**: 사물과 네트워크를 연결한 사물인터넷이다.
- **AI(Artificial Intelligence)**: 데이터에서 학습해 판단하는 인공지능이다.
- **AIoT(Artificial Intelligence of Things)**: IoT 장치에 AI 학습•추론을 결합한 체계이다.

</details>

- 정의/개념: **IoT** 장치와 **AI** 판단의 연쇄 위험을 통제하는 **AIoT** 보안 체계이다.
- 배경/필요성: 기존 IoT 보안만으로는 AI 오판에 따른 물리 피해를 통제할 수 없다.

#### 한줄 요약

- 센서의 잘못된 판단이 문 열림•설비 동작으로 이어지므로 입력부터 물리 제어까지 함께 보호하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **센서 스푸핑**: 물리 신호를 조작해 센서 판단을 왜곡하는 공격이다.
- **적대적 예제**: 입력을 조작해 AI 모델의 오판을 유도하는 공격이다.
- **AI 안전 상태**: 저확신•입력 충돌 시 물리 제어를 제한하는 상태이다.

</details>

- 장치•통신•모델•제어의 연결 경로를 함께 보호한다.
- **센서 스푸핑**•**적대적 예제**에 대비해 입력을 검증한다.
- 추론 불확실성에는 **AI 안전 상태**로 전환한다.

#### 한줄 요약

- 장치 해킹뿐 아니라 AI 확신이 낮거나 입력이 이상할 때 물리 동작을 멈출 기준이 필요하다는 점이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **모델 추출**: 반복 질의와 출력 관찰로 대상 모델의 기능•파라미터를 복제하는 공격이다.
- **모델 드리프트**: 학습•운영 데이터 분포 차이로 모델 판단 성능이 변하는 현상이다.
- **API(Application Programming Interface)**: 시스템 기능을 호출하는 연결 규격이다.
- **AI 모델 통제**: 모델 서명•질의율•호출 권한을 제한하는 통제이다.

</details>

```text
AIoT 보호 구조
├─ 장치 신원•신뢰 기반
├─ 센서 출처•데이터 품질
├─ AI 모델•추론 보호
├─ 통신•플랫폼•API 통제
└─ 액추에이터•안전 관제
```

| 구성요소 | 책임 |
|:---|:---|
| 장치 신원•신뢰 기반 | 고유 신원•보안 부팅•갱신 |
| 센서 출처•데이터 품질 | 진위•범위•다중 센서 대조 |
| AI 모델•추론 보호 | **모델 추출**•**모델 드리프트**와 **AI 모델 통제** |
| 통신•플랫폼•API 통제 | **API** 상호 인증•테넌트 격리 |
| 액추에이터•안전 관제 | 이상•저확신 시 동작 제한 |

#### 한줄 요약

- 신뢰 장치와 검증된 센서 입력만 모델에 넣고 불확실한 결과는 물리 동작으로 전달하지 않음이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **안전 상태 전환**: 입력 이상이나 낮은 확신도를 감지하면 물리 제어를 제한•중지하는 동작이다.
- **AI 추론 증거**: 모델 버전•추론값•확신도와 제어 판단을 기록한 자료이다.
- **장치 신원•입력 일관성 검증**: 출처•시각•다중 센서값을 대조하는 단계이다.
- **모델 추론•확신도 산정**: 승인 모델의 판단값과 불확실성을 계산하는 단계이다.
- **허용 범위•안전 상태 결정**: 물리 영향에 따라 제어 한계와 전환 조건을 정하는 단계이다.
- **제한 제어•안전 전환 실행**: 속도 제한•중지 등 사전 정의된 안전 동작을 수행하는 단계이다.

</details>

```text
장치 신원•시각•원시 센서값
   │
   ▼
1. 장치 신원•입력 일관성 검증
   │ 검증된 입력
   ▼
2. 모델 추론•확신도 산정
   │ 추론값•확신도
   ▼
3. 허용 범위•안전 상태 결정
   ├─ 정상•허용 ──► 제한 내 제어
   └─ 이상•저확신
          │
          ▼
4. 제한 제어•안전 전환 실행
   │
   ▼
안전 상태•실행 결과
```

### 동작 원리

- **1. 장치 신원•입력 일관성 검증**: **장치 신원•입력 일관성 검증**으로 출처•시각•센서값을 대조한다.
- **2. 모델 추론•확신도 산정**: **모델 추론•확신도 산정** 결과를 **AI 추론 증거**로 기록한다.
- **3. 허용 범위•안전 상태 결정**: **허용 범위•안전 상태 결정**으로 제어 한계를 정한다.
- **4. 제한 제어•안전 전환 실행**: **제한 제어•안전 전환 실행**으로 **안전 상태 전환**을 수행한다.

#### 한줄 요약

- 모델의 확신이 낮거나 센서가 충돌하면 자동 제어를 중단하고 사전에 정한 안전 상태로 전환하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **Edge AI**: 장치나 근거리 게이트웨이에서 AI 추론을 수행하는 방식이다.

</details>

| AIoT 추론 위치 | 클라우드 | 엣지 게이트웨이 | 장치 내 |
|:---|:---|:---|:---|
| 적용 기준 | 대규모 연산•중앙 관리 | 현장 지연 단축•전송량 절감 | 저지연•오프라인 동작 |
| 핵심 특징 | 중앙 모델•데이터 운영 | **Edge AI** 기반 근거리 추론 | 개별 장치 즉시 판단 |
| 한계 | 전송•계정•테넌트 노출 | 침해의 장치군 확산 | 모델 추출•자원 부족 |

> 요약: 현장 근접 추론은 지연•전송량을 줄이지만 장치 관리점은 늘어난다.

#### 한줄 요약

- 추론이 현장에 가까울수록 빠르지만 장치별 모델•키•업데이트 보호 지점이 늘어남이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **ISO(International Organization for Standardization)**: 국제표준화기구이다.
- **IEC(International Electrotechnical Commission)**: 국제전기기술위원회이다.
- **ISO/IEC 27400**: IoT 보안•프라이버시 통제 지침이다.
- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **AI RMF(Artificial Intelligence Risk Management Framework)**: AI 위험관리 프레임워크이다.
- **IR(Internal Report)**: NIST의 내부보고서 문서 유형이다.
- **NIST IR 8259**: IoT 제조자의 기본 보안 활동 지침이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 장치와 서비스 통제가 분리되면 경계가 누락됨 | **ISO**•**IEC**의 **ISO/IEC 27400** 적용 | 보안•프라이버시 통제 연계 |
| 모델 성능만 보면 물리 영향이 빠질 수 있음 | **NIST**의 **AI RMF** 적용 | 위험•성능•영향 환류 |
| 판매 전 보안 요구가 없으면 지원 책임이 모호함 | **IR** 유형의 **NIST IR 8259** 적용 | 제조자 활동•지원 명확화 |

#### 한줄 요약

- 센서 이상과 낮은 확신도를 감지하면 제어를 중단하고 모델•펌웨어 버전과 입력 증거를 남겨 원인을 분석한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **경로 전체 보호**: 센서 입력부터 모델 판단과 액추에이터 동작까지 연결해 통제하는 원칙이다.
- **AI 판단 경로**: 센서 입력•모델 추론•물리 동작을 잇는 통제 경로이다.

</details>

- **경로 전체 보호**와 **AI 판단 경로**에 따라 입력 불일치•저확신•고위험이면 자동 제어를 중지한다.

#### 한줄 요약

- 센서 입력부터 AI 판단과 액추에이터 동작까지 한 경로로 보고 이상하면 안전 상태로 전환하는 것이 핵심이다.
