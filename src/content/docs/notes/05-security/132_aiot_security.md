## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **AIoT 보안(AIoT Security / ISO/IEC 27400 & NIST AI RMF)**: 사물인터넷(IoT) 센서 장치에 인공지능(AI/ML) 딥러닝 추론 엔진이 결합된 지능형 사물인터넷(AIoT) 환경에서, 센서 입력 데이터의 위·변조(센서 스푸핑), 딥러닝 모델에 대한 적대적 공격(Adversarial Attacks), 모델 도용(Model Extraction), 그리고 AI 오판으로 인한 물리 액추에이터 오작동 및 인명 사고를 방지하기 위한 하드웨어-소프트웨어-AI 통합 보안 프레임워크.
- **물리 센서 조작에 따른 AI 오판 및 물리적 재난 결함(Sensor-to-Actuation Cascade Defect)**: 전통적인 네트워크 방화벽이 정상 패킷으로 인식하더라도, 공격자가 라이다/카메라 센서에 미세 노이즈를 주입(적대적 예제)하면 엣지 AI 딥러닝 모델이 이를 정상으로 오판하여 로봇 팔이나 자율주행 차량이 잘못된 물리적 제어(급발진, 충돌)를 수행하는 구조적 결함.

</details>

- 정의/개념: 인공지능 사물인터넷의 신뢰성을 보증하기 위해 **하드웨어 RoT 기반 센서 데이터 무결성 검증 $\rightarrow$ 적대적 공격 필터링 및 엣지 AI 추론 보호 $\rightarrow$ 경량 암호화 통신 $\rightarrow$ AI 신뢰도(Confidence) 저하 시 물리 액추에이터 안전 모드(Safe State) 강제 전환 $\rightarrow$ 감사 로그 불변 기록** 을 집행하는 **사이버-물리-AI 융합 보안 아키텍처**
- 배경/필요성: 네트워크 방어만으로는 센서 기만에 따른 **물리 오작동** 차단 불가

#### 한줄 요약
- AIoT 보안은 센서 수집부터 엣지 AI 추론과 물리 액추에이터 제어까지 전주기 무결성을 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **AIoT 3대 핵심 위협 및 방어 기제**:
  - **적대적 예제 방어 (Adversarial Robustness)**: 사람 눈에는 보이지 않는 노이즈를 센서 입력에 주입하여 AI 오판을 유도하는 공격에 대응하여, 입력 정규화 및 적대적 훈련(Adversarial Training) 적용.
  - **센서 교차 검증 (Sensor Fusion & Consistency)**: 카메라, 라이다, 초음파 등 이기종 다중 센서 데이터를 상호 대조하여 단일 센서 스푸핑(Spoofing) 공격 탐지.
  - **안전 상태 폴백 (Safe State Fallback)**: 딥러닝 추론 확신도(Confidence Score)가 임계치 미만으로 하락하거나 센서 간 모순 발생 시 즉각 물리 구동 전원을 차단하고 안전 정지 모드로 전환.

</details>

- 센서·추론·제어를 잇는 **전주기 보호**
- 저전력 MCU/NPU용 **경량 암호·모델 검증**
- 센서값·모델 해시·확신도의 **감사 추적성**

#### 한줄 요약
- 사이버-물리-AI 전주기 보호, 적대적 예제 방어, 다중 센서 퓨전 교차 검증, 안전 상태 폴백을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **AIoT 보안 5대 핵심 아키텍처 계층**:
  1. **Sensor & Hardware Layer**: 하드웨어 RoT, 센서 서명, 물리적 탬퍼 방어.
  2. **Edge AI Inference Layer**: NPU 하드웨어 격리(TrustZone), 모델 지적재산권 암호화.
  3. **Network & API Layer**: 상호 mTLS 인증, REST API 속도 제한(Rate Limiting).
  4. **Cloud & MLOps Platform**: 안전한 모델 재학습 파이프라인, 모델 드리프트(Drift) 모니터링.
  5. **Actuation & Safety Fallback**: 모터/밸브 제어 인터락, 하드웨어 비상 정지 회로.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 센서 수집 및 하드웨어 계층 (Sensor Ingestion & HW RoT) ]           │
│  ├─ [ 하드웨어 RoT ] ➔ 기기 고유 인증서 및 보안 부팅(Secure Boot)       │
│  └─ [ 다중 센서 퓨전 ] ➔ 카메라 + 라이다 + 초음파 입력값 교차 검증     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (검증된 정규화 센서 데이터)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 엣지 AI 추론 및 모델 보호 계층 (Edge AI & Adversarial Defense) ]   │
│  ├─ [ 모델 보호 ] ➔ AES 암호화된 딥러닝 가중치 + TEE 내부 복호화 실행    │
│  ├─ [ 적대적 방어 ] ➔ 입력 이미지 스무딩 및 노이즈 필터링               │
│  └─ [ 확신도 산출 ] ➔ 추론 결과 클래스별 확률값(Confidence Score) 계산  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (추론 결과 및 신뢰도 스코어)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 안전 제어 및 폴백 판정 계층 (Safety Interlock & Safe Fallback) ]    │
├───────────────────────────────────┬─────────────────────────────────────┤
│ [ 정상 제어 (Confidence $\ge$ 85%) ]│ [ 안전 폴백 (Confidence < 85%) ]    │
│ ├─ 다중 센서 데이터 일치 확인     │ ├─ 센서 간 충돌 및 저확신 오판 감지 │
│ └─ 모터 액추에이터 구동 승인       │ └─ [ 액추에이터 즉시 비상 정지 락킹]│
└───────────────────────────────────┴─────────────────────────────────────┘
                                     │ (상태 텔레메트리 전송: mTLS 1.3)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 클라우드 MLOps 및 감사 계층 (Cloud Platform & Immutable Audit) ]    │
│  ├─ [ 모델 드리프트 감시 ] ➔ 실환경 성능 저하 탐지 시 자동 재학습 파이프라인│
│  └─ [ 불변 감사 원장 ] ➔ 센서값, 모델 버전, 추론 확신도 영구 기록      │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 센서 입력을 교차 검증하여 엣지 AI에서 추론하고, 확신도에 따라 정상 제어 또는 비상 정지 폴백을 집행하며 클라우드에서 감사하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **센서·하드웨어** | RoT와 센서 퓨전으로 입력 무결성 검증 |
| **엣지 AI 엔진** | TEE 격리 추론과 모델 암호화 |
| **통신·API** | mTLS와 질의율 제한으로 연결 보호 |
| **물리 액추에이터** | 인터락과 비상 정지로 안전 상태 보장 |
| **클라우드 MLOps** | 모델 드리프트 감시와 감사 로그 관리 |

#### 한줄 요약
- 센서 하드웨어, 엣지 AI 추론, 통신 API, 물리 액추에이터 안전 제어, 클라우드 MLOps로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **AIoT 자율 제어 및 안전 폴백 5단계 프로세스**:
  1. 센서 데이터 수집 및 다중 센서 상호 일관성 검증
  2. 엣지 TEE 내부에서 적대적 노이즈 필터링 및 딥러닝 추론 수행
  3. 추론 결과의 확신도(Confidence Score) 산출
  4. 확신도 및 안전 규칙에 따른 물리 액추에이터 제어 또는 비상 정지 분기
  5. 제어 파라미터 및 추론 증적의 클라우드 MLOps 감사 로깅

</details>

```text
1. [센서 데이터 수집] 자율주행 차량 라이다 및 카메라 센서에서 전방 장애물 프레임 수집
            │
            ▼
2. [센서 교차 검증 및 필터링]
    ├─ 카메라(보행자 감지) vs 라이다(거리 5m 감지) 데이터 일관성 확인
    └─ [가우시안 필터링을 통해 적대적 미세 노이즈 사전 제거]
            │
            ▼
3. [엣지 AI 추론 연산]
    ├─ ARM TrustZone 보안 영역 내에서 양자화된 CNN 객체 인식 모델 실행
    └─ [추론 결과: "보행자 감지", 확신도 점수: 96% 산출]
            │
            ▼
4. [안전 인터락 및 물리 제어]
    ├─ [정상 판정 (확신도 $\ge$ 85%)] ➔ 브레이크 액추에이터에 비상 제동 신호 인가 (차량 정지)
    └─ (만약 악천후로 확신도 40% 도출 시 ➔ 페일세이프(Fail-safe) 비상 깜빡이 점등 후 감속)
            │
            ▼
5. [클라우드 증적 로깅 및 환류]
    ├─ 당시 센서 스냅샷 + AI 모델 v1.4 해시 + 확신도 96%를 암호화하여 로컬/클라우드 저장
    └─ [MLOps 파이프라인에서 해당 케이스를 수집하여 차기 모델 훈련 데이터셋 반영]
```

**동작 원리**

1. **센서 데이터 수집**: 이기종 센서 입력 획득
2. **센서 교차 검증 및 필터링**: 불일치와 적대 노이즈 제거
3. **엣지 AI 추론 연산**: TEE에서 결과와 확신도 산출
4. **안전 인터락 및 물리 제어**: 규칙에 따라 제어·폴백 선택
5. **클라우드 증적 로깅 및 환류**: 증적 저장과 재학습 반영

#### 한줄 요약
- 센서 수집, 교차 검증, TEE 엣지 추론, 안전 인터락 제어, MLOps 감사 로깅 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **AIoT 3대 추론 아키텍처 모델 비교**:
  - 클라우드 AI (Cloud AI): 센서 데이터를 클라우드로 전송하여 거대 모델 연산 (지연시간 높음, 중앙 집중).
  - 엣지 AI 게이트웨이 (Edge AI): 로컬 게이트웨이에서 중간 규모 모델 추론 (로컬 네트워크 의존).
  - 온디바이스 AI (On-device TinyML): 초소형 마이크로컨트롤러(MCU) 내부에서 단독 추론 (초저지연, 완전 독립).

</details>

| 비교 항목 | 클라우드 AI (Cloud AI) | 엣지 게이트웨이 AI (Edge AI) | 온디바이스 AI (TinyML) |
|:---|:---|:---|:---|
| **연산 위치** | **원격 대규모 클라우드 데이터센터** | **로컬 라우터/게이트웨이 서버** | **단말 센서 내부 저전력 MCU/NPU** |
| **응답 레이턴시** | 높음 (수백 ms ~ 수 초) | 중간 (수십 ms) | **초저지연 (수 ms 이내 즉각 응답)** |
| **통신 의존도** | **100% 인터넷 연결 필수 (단절 시 마비)**| 로컬 LAN 연결 필요 | **0% (완전 오프라인 독립 구동)** |
| **데이터 프라이버시**| 낮음 (민감 센서 영상 외부 전송) | 중간 (로컬 네트워크 내 처리) | **최상 (원천 데이터 외부 유출 0%)** |
| **주요 보안 위험** | 데이터 전송 중 도청, 멀티테넌트 침해 | 게이트웨이 장악 시 전 하위 기기 침해| **물리적 디바이스 덤프 및 모델 추출**|

#### 한줄 요약
- 클라우드 AI는 거대 모델 중앙 처리, 엣지는 로컬 분산 처리, 온디바이스 TinyML은 초저지연 오프라인 처리에 특화된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/IEC 27400 (IoT 보안 가이드) 및 NIST AI RMF 1.0 (AI 위험 관리 프레임워크)**: 사물인터넷 및 인공지능 신뢰성/안전성 국제 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공격자가 자율주행 도로 표지판에 미세 스티커를 부착하는 **적대적 예제(Adversarial Example) 공격으로 인해 AI가 정지 신호를 인식하지 못하고 사고 발생** | **입력 이미지 정규화 및 적대적 훈련(Adversarial Training)을 적용하고, 라이다/정밀지도 다중 센서 퓨전 교차 검증 강제** | AI 시각 인식 적대적 공격 저항성 95% 이상 확보 |
| IoT 단말 보드를 물리적으로 분해하여 플래시 메모리에서 **수억 원의 개발 비용이 투입된 독자 AI 딥러닝 모델 가중치를 무단 복제(Model Theft)** | **ARM TrustZone TEE 내부 메모리에서만 딥러닝 모델을 복호화하고, 모델 가중치 난독화 및 워터마킹(Watermarking) 적용** | 모델 지적재산권 유출 100% 원천 차단 |
| 현장 운영 중 데이터 분포 변화(Data Drift)로 AI 정확도가 저하되어 **스마트 팩토리 산업용 로봇 팔이 작업자를 감지하지 못하는 오판 위험 발생** | **NIST AI RMF 기반 MLOps 파이프라인 구축, 확신도 85% 미만 시 모터 전원을 차단하는 하드웨어 안전 인터락(Interlock) 구축** | 오판으로 인한 물리적 인명 사고 100% 원천 예방 |

#### 한줄 요약
- 적대적 훈련으로 시각 공격을 막고, TEE 암호화로 모델 도용을 방어하며, 안전 인터락으로 물리 사고를 예방한다.

## Ⅶ. 결론

- 저확신·센서 불일치 시 **안전 상태 폴백**, 정상 시에만 제어 허용

#### 한줄 요약
- 하드웨어 RoT 센서 검증과 TEE 엣지 모델 보호 및 안전 폴백 인터락을 통해 완벽한 AIoT 보안을 완성한다.
