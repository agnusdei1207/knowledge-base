## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **FIDO2 (Fast Identity Online 2)**: 털리기 딱 좋은 비밀번호 좀 그만 쓰고, 스마트폰 지문이나 얼굴 인식(공개키 암호화)으로 안전하게 로그인하자는 글로벌 팩트 표준이다. (피싱 철벽 방어)
- **WebAuthn (웹 인증)**: "브라우저(크롬)야, 나 로그인할 거니까 사용자한테 지문 인식창 좀 띄워줘!" 하고 웹사이트가 브라우저에게 팩트로 부탁하는 표준 자바스크립트 API 규격이다.
- **RP (신뢰 당사자, Relying Party)**: 네이버나 구글처럼, 사용자의 지문 서명이 맞는지 자물쇠(공개키)로 확인하고 로그인을 승인해 주는 실제 서비스 백엔드 서버다.

</details>

- 정의: 비밀번호 없이 비패스워드(Passwordless) 및 피싱 저항성(Phishing-Resistant) 공개키 기반 인증을 제공하는 W3C 및 FIDO 얼라이언스의 국제 팩트 표준이다.
- 배경: 비밀번호나 SMS OTP 같은 '공유 비밀'은 중간자 해커가 똑같이 생긴 가짜 사이트(피싱)로 낚아서 훔쳐 가면 그대로 팩트로 털리기 때문이다.

#### 한줄 요약

- 해커가 가짜 사이트 만들어도, 브라우저가 주소 까보고 "어 가짜네?" 하고 지문 서명을 안 해버리는 팩트 방어다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **RP ID (도메인 바인딩)**: 내 지문 열쇠(개인키)는 오직 진짜 'naver.com'에서만 열리고, 해커가 파놓은 가짜 'naaver.com'에선 아예 작동조차 안 하게 팩트로 묶어버리는 피싱 방어의 핵심이다.
- **사용자 검증(UV) 및 존재(UP)**: 폰을 주운 딴놈이나 원격 해커가 못 열게, "지문(얼굴) 대봐(UV)", "물리 버튼 눌러봐(UP)" 하고 내 몸과 물리적 터치를 팩트로 확인하는 과정이다.

</details>

- **팩트 하드웨어 칩 격리**: 개인키(열쇠)는 클라이언트 하드웨어 보안 칩셋(Secure Enclave/TPM)에 절대 안 털리게 격리하고, RP 서버에는 자물쇠(공개키)만 팩트 등록한다.
- **팩트 피싱 원천 차단 (도메인 바인딩)**: 브라우저가 현재 접속한 주소(Origin)와 서버가 보낸 RP ID가 1글자라도 다르면 전자서명 자체를 안 해버려서, 피싱 공격을 구조적으로 팩트 차단한다.
- **팩트 생체 및 물리적 검증**: 폰을 해킹한 해커가 원격으로 승인하지 못하게, 사용자 검증(UV)과 버튼 누름(UP)을 통해 물리적 타당성을 팩트로 강제한다.

#### 한줄 요약

- 열쇠는 내 폰(TPM)에 숨기고, 진짜 사이트(도메인)에서 지문 댈 때만 서명해 주는 완벽한 팩트 방어 체계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인증자 (Authenticator)**: 내 폰(아이폰/갤럭시)이나 USB 보안키처럼, 실제로 내 지문을 읽고 하드웨어 보안 칩에서 개인키로 전자서명을 팩트로 찍어주는 장비다.
- **CTAP2**: 컴퓨터(크롬 브라우저)랑 내 스마트폰(또는 보안키)이 블루투스나 USB로 대화할 때 쓰는 팩트 통신 언어 규격이다.

</details>

```text
[ FIDO2 / WebAuthn 팩트 동작 아키텍처 ]

[ 1. RP 서버 (네이버 등) ] ── ("도전값(난수) 만들어서 브라우저한테 던져주고 서명해 오라고 팩트 지시함")
      │
      ▼
[ 2. WebAuthn 클라이언트 (크롬 브라우저) ] ── ("가짜 사이트 아닌지 도메인(Origin) 팩트 체크하고 인증자 호출함")
      │
      ▼
[ 3. 인증자 (스마트폰 지문센서 / 보안키) ] ── ("주인이 지문 대면, 비밀 금고(TPM) 열어서 개인키로 팩트 서명함")
      │
      ▼
[ 4. 자격 증명 저장소 (DB) ] ── ("RP 서버가 자물쇠(공개키) 모아두는 곳. 여기서 꺼내서 서명 팩트 대조함")
      │
      ▼
[ 5. 인증기 수명 관리 ] ── ("스마트폰 바꾸거나 잃어버렸을 때 대충 복구 안 해주고 빡세게 팩트 관리함")
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **RP 서버 (백엔드)** | "가짜 말고 너 본인 맞으면 서명해와!" 하고 **도전값(난수) 발급 및 서명 팩트 검증함** | RP |
| **WebAuthn 클라이언트** | 브라우저가 주소창(Origin)을 까보고 **가짜 피싱 사이트면 서명 요청을 팩트 컷함** | Browser |
| **인증자 (Authenticator)** | 해커가 못 훔쳐가는 하드웨어 칩에서 **생체(지문) 인식하고 개인키로 팩트 서명함** | Device |
| **자격 증명 저장소** | RP 서버가 사용자별로 로그인 승인에 쓸 **공개키(자물쇠)를 DB에 팩트로 저장해둠** | DB |
| **인증기 수명 통제** | 스마트폰 분실 시 **기존 키 폐기 및 새로운 기기 인증을 엄격한 절차로 팩트 관리함** | Lifecycle |

#### 한줄 요약

- 서버가 문제(난수) 내면 $\to$ 브라우저가 사이트 짭인지 확인하고 $\to$ 폰이 지문 찍고 답안지(서명) 제출한다.

## Ⅳ. 흐름도

```text
[ FIDO2 피싱 저항성 팩트 인증 흐름 ]

┌──────────────────────────────┐
│ 1. [도전값(Challenge) 및 RP 정책 팩트 생성]
│ ("서버가 Replay 공격(재전송) 방어용 난수(도전값)를 클라이언트로 팩트 발송함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [WebAuthn: 원본(Origin) 및 RP ID 팩트 검증]
│ ("브라우저: '어? 접속 주소는 naaver(가짜)인데, RP ID는 naver네?' 불일치 시 즉각 팩트 컷!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [인증자: 사용자 존재(UP) 및 검증(UV) 팩트 확인]
│ ("진짜 사이트면, 스마트폰이 '지문 대세요' 하고 본인 생체와 승인 의사를 팩트로 확인함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [인증자: 개인키 팩트 전자 서명 생성]
│ ("지문 통과! 내부 하드웨어 칩(Secure Enclave)이 개인키를 꺼내서 도전값을 팩트 서명함")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 5. [RP 서버: 공개키 기반 서명 팩트 대조 및 승인]
    │ ("서버가 등록된 공개키(자물쇠)로 서명을 열어보고, 이상 없으면 로그인 팩트 승인!")
    └──────────────────────────────┘
```

### 동작 원리

1. 정책 생성: RP 서버가 피싱 및 재전송 방지를 위한 Challenge 난수와 자격증명 옵션을 생성.
2. 도메인 바인딩(WebAuthn): 브라우저 런타임이 현재 접속 Origin과 RP ID의 불일치를 팩트 판정.
3. 생체 검증(UV/UP): 인증자가 팝업을 띄워 생체인식 및 버튼 누름 등 물리적 행위를 팩트 확인.
4. 서명 생성(CTAP2): 하드웨어 격리 영역 내부의 개인키로 Challenge 및 ClientData를 팩트 서명.
5. 서버 대조(RP): RP 서버가 DB에 등록된 공개키로 최종 서명 검증 후 안전 세션을 팩트 발급.

#### 한줄 요약

- 가짜 사이트면 브라우저가 자르고, 원격 해커면 지문에서 자르고, 재전송 공격은 난수 서명으로 팩트 자른다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 구성 요소 분류 | **FIDO2 (전체 팩트 표준)** | **WebAuthn (W3C 스펙)** | **CTAP2 (FIDO 얼라이언스 스펙)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **비밀번호 없애버리자고 만든 '거대한 설계 규칙'** | **웹 서버와 크롬 브라우저 간의 '대화 통역기'** | **크롬 브라우저와 USB 보안키/스마트폰 간의 '통신 케이블'** |
| 핵심 역할 및 기능 | 패스워드리스(Passwordless)와 피싱 저항성을 보장하는 **공개키 인증 최상위 팩트 프레임워크** | 브라우저(JS API)가 서버(RP)와 **인증 서명 데이터를 안전하게 주고받게 팩트 중계함** | 브라우저가 스마트폰(NFC/BLE)이나 하드웨어(USB) 인증자와 **대화하게 해주는 팩트 규격** |
| 연계 및 적용 지점 | **이 두 가지 하위 규격(WebAuthn + CTAP2)을 합쳐서 부르는 통합 명칭임** | 서비스 도메인(Origin)을 까보고 **진짜 사이트가 맞는지 팩트 검증하는 프론트엔드 핵심** | 내장된 지문 센서나 외부 YubiKey 같은 **물리적 인증 장비를 팩트로 구동하는 백엔드 코어** |

#### 한줄 요약

- 큰 그림이 **FIDO2**고, 브라우저가 일하는 게 **WebAuthn**, 기계끼리 통신하는 게 **CTAP2** 규격이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C WebAuthn Level 2/3**: 애플 기기간 연동되는 패스키(Passkey) 등 최신 생태계 호환성을 지원하는 웹 인증 스펙이다.
- **XSS (교차 사이트 스크립팅)**: 해커가 게시판에 자바스크립트를 숨겨서 내 브라우저 안에서 몰래 "지문 인식창 띄워!" 하고 FIDO API를 팩트로 찔러보는 얍삽한 해킹 공격이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| FIDO2로 개발했는데 **아이폰이나 구형 안드로이드에서 팩트로 에러가 남** | 브라우저나 디바이스 OS마다 WebAuthn API 지원 수준이 달라서 플랫폼 파편화가 팩트로 발생함 | **W3C WebAuthn Level 2** 이상 표준 스펙을 준수하고, 구형 대비 하위 호환성(Fallback) 팩트 확보 | 애플/구글 생태계의 패스키(Passkey) 호환성 및 끊김 없는 사용자 경험(UX) 팩트 보장 |
| FIDO 철통 방어 쳐놨는데 **게시판 XSS 취약점 땜에 지문 창이 미친 듯이 팩트로 뜸** | 공격자가 XSS 스크립트를 이용해 신뢰할 수 있는 도메인(Origin) 위에서 강제로 WebAuthn 팩트 호출 | JS 인젝션을 막는 **CSP (콘텐츠 보안 정책)** 헤더 팩트 적용 및 백엔드 XSS 취약점 원천 제거 | 신뢰 출처(Origin) 상에서의 무단 생체 인증 호출(Prompt Spam) 팩트 원천 방어 |
| 사장님이 스마트폰 잃어버렸다고 **로그인 못 해서 메인 서버 업무가 팩트로 올스톱됨** | FIDO 개인키는 폰 안에 물리적으로 갇혀 있어서, 기기 분실 시 계정 접근 수단이 팩트로 증발함 | 복수 인증자(기기 2대 이상 패스키) 사전 등록 유도 및 **엄격한 계정 복구(Recovery) 절차 팩트 수립** | 기기 분실로 인한 서비스 영구 잠금(Lockout) 방지 및 허술한 복구 경로 우회 팩트 차단 |

#### 한줄 요약

- 브라우저별 호환성 맞추고, XSS로 알람 폭탄 못 날리게 막고, 폰 분실 대비 백업 기기(패스키) 등록시켜라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **인증자 수명 관리 (Authenticator Lifecycle Management)**: 폰 바꿀 때 새 폰 등록하고 옛날 폰 쳐내는 등, 기기(열쇠)의 일생을 철저하게 팩트로 관리하는 보안 정책.

</details>

- 비밀번호의 치명적 한계를 극복하기 위해, 피싱 저항이 필수적인 제로 트러스트 환경에는 도메인 바인딩 기반의 **FIDO2/WebAuthn**을 전면 적용하고, 기기 분실에 대비해 **복수 인증자 등록**과 메인 인증에 준하는 엄격한 **인증자 수명 관리(복구 절차)** 로 백도어 취약점을 다층 팩트 차단하는 실무 기조를 확립함

#### 한줄 요약

- 피싱 저항은 **FIDO2/WebAuthn**, 기기 분실 대비는 **인증자 수명 관리(복구 정책)** 로 팩트 통제해라.
