## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **전자서명(Digital Signature)**: 송신자가 메시지의 암호학적 해시값(다이제스트)을 자신의 비대칭 개인키(Private Key)로 암호화하여 서명값(Signature)을 생성하고, 수신자는 송신자의 검증된 공개키(Public Key)로 이를 복호화·대조하여 송신자 신원과 메시지 위변조 여부를 증명하는 기술.
- **부인방지(Non-Repudiation)**: 송신자만이 독점 보유한 개인키로 서명되었음이 암호학적으로 입증되므로, 사후에 송신자가 해당 전자문서를 작성하거나 승인하지 않았다고 법률적·기술적으로 부인할 수 없도록 강제하는 특성.

</details>

- 정의/개념: 비대칭 암호화 기술과 암호학적 해시 함수를 결합하여, 전자문서의 **위변조 방지(무결성)**, **작성자 신원 증명(인증)**, **사후 서명 부인 차단(부인방지)** 을 수학적으로 보증하는 **공개키 기반 디지털 신뢰 프레임워크**
- 배경/필요성: 서명 없는 전자문서나 단순 해시값만으로는 문서 작성자의 신원을 증명할 수 없고 문서 변조 시 책임 소재 규명이 불가능한 정보 유통의 한계를 극복할 요구

#### 한줄 요약
- 개인키로 해시값을 암호화하고 공개키로 검증하여 무결성, 인증, 부인방지를 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **확률적 서명(Probabilistic Signature / RSA-PSS)**: 결정론적 서명(동일 평문에 항상 동일 서명값 출력)의 취약점을 제거하기 위해, 서명 연산 시 무작위 솔트(Salt)를 주입하여 매번 완전히 다른 서명값을 생성하는 표준 서명 기법 (RFC 8017).
- **문서 정규화(Canonicalization / C14N)**: XML, JSON 등 구조화된 문서에서 공백, 줄바꿈, 속성 순서의 차이로 인해 해시값이 달라져 서명 검증이 실패하는 것을 방지하기 위해 표준 바이트열로 변환하는 전처리 작업.

</details>

- **비대칭 키 역할의 역전**: 암호화 통신과 반대로, 송신자가 개인키로 서명(Sign)하고 수신자는 공개키로 검증(Verify)
- **보안 3대 핵심 속성 동시 충족**: 무결성(Integrity), 출처 인증(Authentication), 법적 부인방지(Non-Repudiation) 완벽 보장 (단, 기밀성은 미제공)
- **하드웨어 격리 서명 집행 (HSM 연동)**: 서명용 개인키를 일반 서버 메모리에 로드하지 않고 FIPS 140-3 HSM 내부에서 연산 수행

#### 한줄 요약
- 개인키 서명·공개키 검증, 보안 3요소(무결성/인증/부인방지) 충족, RSA-PSS/ECDSA/ML-DSA 표준을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **타임스탬프 토큰(Time-Stamp Token, TSA / RFC 3161)**: 공인 신뢰 시각 기관(TSA)이 문서 다이제스트와 공인 시각을 결합하여 서명함으로써, 특정 시점에 해당 문서가 존재했음(존재 증명)과 당시 인증서가 유효했음을 영구 증명하는 장기 검증(LTV) 토큰.

</details>

```text
[ 송신자 (Signer) ]
 ├─ 원본 전자문서 (Plain Document) ──▶ [ 문서 정규화 (C14N) ] ──▶ [ 해시 함수 (SHA-256) ]
 └─ 개인키 (Private Key: HSM 내 보관) ──────────────────────────────▶ [ 서명 생성 엔진 ] ──▶ [ 서명값 (Signature) ]
                                                                                               │
                                    (전자문서 + 서명값 + X.509 인증서 전송) ────────────────────┘
                                    │
                                    ▼
[ 수신자 (Verifier) ]
 ├─ 1. 수신 문서 ──▶ [ 동일 C14N 정규화 ] ──▶ [ SHA-256 해시 연산 ] ──▶ [ 계산된 다이제스트 $H_1$ ]
 │                                                                                  │
 └─ 2. 수신 서명값 ──▶ [ X.509 공개키 검증 ] ──▶ [ 복호화 다이제스트 $H_2$ ] ─────────┼──▶ [ $H_1 == H_2$ 비교 ]
                                                                                    │     ├─ 일치: 서명 유효 (Pass)
                                                                                    │     └─ 불일치: 변조/위조 (Fail)
```

선의 의미: 송신자가 정규화된 문서 해시를 개인키로 서명하여 전송하고, 수신자가 공개키로 복호화한 해시값과 원문 해시값을 비교 판정하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **문서 정규화 모듈 (C14N)**| XML/JSON/PDF 문서의 공백 및 인코딩을 정형화하여 일관된 해시 입력 보장 | W3C C14N |
| **암호학적 해시 엔진** | 원본 문서를 256/384비트 고정 크기 메시지 다이제스트로 단방향 압축 | SHA-256 / SHA-3 |
| **HSM 서명 연산기** | 개인키 탈취를 물리적으로 차단하고 하드웨어 내부에서 서명값($S$) 생성 | FIPS 140-3 |
| **X.509 인증서 저장소** | 서명자의 신원과 공개키의 유효성을 증명하는 PKI 인증서 및 CRL/OCSP | PKI Repository |
| **타임스탬프 서버 (TSA)** | 공인 시각 인증서를 결합하여 서명 시점을 증명하고 장기 검증(LTV) 제공 | RFC 3161 TSA |

#### 한줄 요약
- 정규화 모듈, 해시 엔진, HSM 서명 연산기, X.509 인증서, TSA 타임스탬프가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **장기 검증(Long Term Validation, LTV / PAdES-LTV)**: 수년 후 서명자의 인증서가 만료되거나 폐기되더라도, 서명 당시의 유효했던 OCSP 응답과 TSA 토큰을 문서 내에 영구 임베딩하여 사후 법적 효력을 유지하는 기법.

</details>

```text
1. 송신자가 전자문서를 C14N 알고리즘으로 정규화하고 SHA-256 다이제스트($H$) 추출
            │
            ▼
2. HSM 내부의 256비트 개인키로 다이제스트를 서명 연산(ECDSA/RSA-PSS)하여 서명값($S$) 생성
            │
            ▼
3. 공인 TSA 서버로부터 타임스탬프 토큰을 발급받아 문서에 첨부 ➔ [문서 + 서명값 + 인증서 + TSA] 패키징 송신
            │
            ▼
4. 수신자가 서명자의 X.509 인증서 경로 및 실시간 폐기 상태(OCSP) 유효성 검증
            │
            ▼
5. 수신 문서의 SHA-256 해시값과 공개키로 검증한 서명값 일치 판정 ➔ 무결성, 출처 인증, 부인방지 확정
```

**동작 원리**

1. **정규화 및 해싱**: 문서 포맷의 사소한 불일치로 인한 서명 실패를 방지하고 해시 생성
2. **개인키 암호 서명**: 오직 서명자만이 알고 있는 비밀값($d$)과 임시 난수($k$)를 사용하여 서명 페어($r, s$) 산출
3. **인증서 체인 검증**: 수신자가 Root CA까지의 인증서 서명을 역추적하여 서명자의 정당성 확인
4. **수학적 서명 검증**: 공개키($Q$)와 해시($e$)를 대조하여 $r \equiv (e \cdot s^{-1} \cdot G + r \cdot s^{-1} \cdot Q)_x \pmod n$ 검증
5. **법적 효력 확정**: 타임스탬프 기록을 통해 서명 시점의 유효성을 고정하여 사후 부인 차단

#### 한줄 요약
- C14N 정규화, 해시 추출, HSM 개인키 서명, X.509/OCSP 검증, 수학적 서명 일치 판정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전자서명 알고리즘 세대별 비교**: 전통적 RSA-PSS, 초경량 타원곡선 ECDSA/Ed25519, 차세대 양자내성 ML-DSA(Dilithium)의 비교.

</details>

| 비교 항목 | RSA-PSS (RFC 8017) | ECDSA / Ed25519 (RFC 8032) | ML-DSA (NIST FIPS 204) |
|:---|:---|:---|:---|
| **수학적 기반** | **소인수분해 난제 + PSS 확률적 패딩**| **타원곡선 이산대수 (ECDLP / Curve25519)**| **모듈 격자 상의 학습 난제 (MLWE)** |
| **서명 크기** | **384 바이트 (RSA 3072비트 기준, 큼)** | **64 바이트 (256비트 기준, 극도로 작음)**| **2,420 바이트 (양자내성 구조, 큼)** |
| **서명/검증 속도** | 서명 연산 무거움, 검증 빠름 | **서명 및 검증 모두 극도로 빠름** | 고속 격자 다항식 연산 지원 |
| **난수(k) 오류 취약성**| 안전 (결정론적/확률적) | **위험 (RFC 6979 미적용 시 개인키 유출)**| 안전 (결정론적 서명 지원) |
| **양자 공격 저항성** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **영구적 안전 (양자 컴퓨터 내성)** |
| **주요 적용 분야** | 공인 전자문서, 코드 서명(Code Sign)| **TLS 1.3, 블록체인(비트코인/이더리움)** | **차세대 국가 기밀, 장기 보존 전자문서** |

#### 한줄 요약
- RSA-PSS는 레거시 호환, ECDSA/Ed25519는 고속 경량 표준, ML-DSA는 양자 공격 대비 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ECDSA 논스 재사용/유출 취약점(Sony PS3 사태)**: ECDSA 서명 연산 시 1회용 난수 $k$를 고정값으로 재사용하거나 편향된 난수를 사용할 경우, 공격자가 2개의 서명값 차분을 통해 개인키 $d$를 대수적으로 즉시 추출하는 치명적 결함.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ECDSA 서명 시 난수($k$) 재사용 또는 편향으로 인한 **서명자의 개인키 즉시 유출 사고** | **RFC 6979 결정론적(Deterministic) k 생성 또는 Ed25519(EdDSA)** 알고리즘 강제 | 난수 결함 원천 제거 및 개인키 노출 확률 0% 달성 |
| 소프트웨어 공급망 공격 시 빌드 서버의 서명키 탈취로 인한 **악성코드 위조 서명 배포** | 서명키를 **FIPS 140-3 Level 3 HSM에 격리하고 CI/CD 다중 승인(Quorum) 서명** 강제 | 서명키 비인가 반출 차단 및 SolarWinds형 공급망 공격 완벽 차단 |
| 수년 후 인증서 만료 및 폐기로 인해 과거 체결된 **전자계약서의 법적 부인방지 효력 상실** | **RFC 3161 TSA 타임스탬프 및 LTV(PAdES-LTV) 검증 아티팩트 영구 임베딩** | 인증서 만료 후에도 수십 년간 완전한 법적 증거력 및 진본성 보존 |

#### 한줄 요약
- RFC 6979로 개인키 유출을 막고, HSM/다중 승인으로 공급망을 방어하며, TSA/LTV로 장기 증거력을 보증한다.

## Ⅶ. 결론

- 디지털 트랜스포메이션 환경에서 데이터의 진본성과 법적 효력을 보장하기 위해 **전자서명 아키텍처**는 모든 신뢰 서비스(인증서, 블록체인, 코드 서명, 공공 전자문서)의 핵심 기틀이며, 실무 구현 시 **결정론적 Ed25519/RSA-PSS 표준화**, **HSM 기반 개인키 무결점 보호**, **LTV 타임스탬프 결합**, **PQC(ML-DSA) 양자내성 서명 전환**을 선제 추진하여 지속 가능한 디지털 신뢰 생태계를 완성

#### 한줄 요약
- 비대칭 개인키 서명과 해시 무결성 및 TSA 타임스탬프를 결합하여 법적 부인방지와 신원 인증을 실현한다.
