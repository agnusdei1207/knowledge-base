## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Digital Signature (전자서명)**: 메시지 해시값을 송신자의 개인키로 암호화하여 작성자 신원과 무결성을 증명하는 기술.
- **Non-Repudiation (부인방지)**: 소유자만의 개인키로 서명되었음이 증명되어 사후에 송신 사실을 부인할 수 없도록 강제하는 법적·기술적 속성.

</details>

- 정의/개념: 비대칭 개인키 암호화와 해시 함수를 결합하여 **전자문서의 무결성, 출처 인증, 부인방지를 수학적으로 보증하는 공개키 신뢰 기술**
- 배경/필요성: 평문 전자문서 및 단순 해시값의 **작성자 신원 증명 불가, 제3자 위변조 취약성 및 법률적 부인방지 효력 부재**

#### 한줄 요약
- 개인키 서명과 공개키 검증을 통해 전자문서의 무결성, 인증, 부인방지를 보증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Ed25519 (EdDSA, RFC 8032)**: Curve25519 기반의 결정론적 전자서명으로, 난수 재사용 취약점을 원천 제거하고 64바이트 초소형 서명을 제공하는 현대 표준.
- **TSA (Time Stamping Authority, RFC 3161)**: 전자문서가 특정 시점에 확실히 존재했음을 공인 시각 인증서로 증명하는 신뢰 기관.

</details>

- **3대 보안 속성의 완벽한 보증**: 전자문서의 **위변조 방지(무결성), 서명자 신원 확인(인증), 법적 송신 사실 입증(부인방지)**
- **결정론적 서명(RFC 6979 / EdDSA)**: 외부 난수 생성 결함에 영향받지 않고 **개인키와 메시지 해시로부터 $k$값을 결정론적 유도**
- **타임스탬프 결합 장기 검증(LTV)**: RFC 3161 TSA를 연계하여 **인증서 만료 후에도 수십 년간 사후 법적 증거력 영구 보존**

#### 한줄 요약
- 3대 보안 속성 보증, 결정론적 서명을 통한 개인키 보호, TSA 결합 장기 검증(LTV)을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Canonicalization (C14N, 문서 정규화)**: XML/JSON/PDF의 공백, 인코딩, 줄바꿈을 정형화하여 동일한 해시값이 산출되도록 보장하는 전처리.

</details>

```text
[전자서명 생성 및 공개키 검증 파이프라인]
|-- Signer (송신자: 원본 문서 -> C14N 정규화 -> SHA-256 해시 -> HSM 개인키 서명 -> 서명값 S)
`-- Document Package Transmission (전자문서 + 서명값 S + X.509 인증서 + TSA 타임스탬프)
`-- Verifier (수신자 검증 프로세스)
    |-- 1. 수신 문서 -> C14N 정규화 -> SHA-256 해시 연산 -> [ 계산된 다이제스트 H_1 ]
    |-- 2. 수신 서명값 -> X.509 공개키 검증 연산 -> [ 복호화 다이제스트 H_2 ]
    `-- 3. H_1 == H_2 일치 판정 (일치: 서명 유효 Pass / 불일치: 변조 Fail)
```

선의 의미: 송신자가 정규화된 문서 해시를 개인키로 서명하여 전송하고 수신자가 공개키로 복호화한 해시값과 원문 해시값을 비교 판정하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **문서 정규화 모듈 (C14N)**| XML/JSON/PDF의 공백/인코딩을 정형화하여 **일관된 해시 입력 보장** | W3C C14N |
| **암호학적 해시 엔진** | 원본 문서를 **256/384비트 고정 크기 다이제스트로 단방향 압축** | SHA-256 / SHA-3 |
| **HSM 서명 연산기** | 개인키 탈취를 물리적으로 차단하고 **하드웨어 내부에서 서명값($S$) 생성** | FIPS 140-3 |
| **X.509 인증서 저장소**| 서명자의 신원과 공개키의 유효성을 증명하는 **PKI 인증서 및 CRL/OCSP** | PKI Repository |
| **타임스탬프 서버 (TSA)**| 공인 시각 인증서를 결합하여 **서명 시점을 증명하고 장기 검증(LTV) 제공** | RFC 3161 TSA |

#### 한줄 요약
- 정규화 모듈, 해시 엔진, HSM 서명 연산기, X.509 인증서, TSA 타임스탬프가 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PAdES-LTV (PDF Advanced Electronic Signatures LTV)**: PDF 문서 내에 서명 시점의 인증서 체인, OCSP 응답, TSA 토큰을 영구 포함시켜 미래에도 검증을 보장하는 포맷.

</details>

```text
전자서명 생성, TSA 결합, 패키지 전송 및 수학적 검증 파이프라인
        │
   1. [문서 정규화 및 해싱] 전자문서를 C14N 알고리즘으로 정규화하고 SHA-256 다이제스트($H$) 추출
        │
   2. [HSM 개인키 서명] HSM 내부의 256비트 개인키로 다이제스트를 서명 연산(Ed25519/RSA-PSS)하여 서명값($S$) 생성
        │
   3. [TSA 타임스탬프 결합] 공인 TSA로부터 시각 토큰을 발급받아 [문서 + 서명값 + 인증서 + TSA] 패키지 전송
        │
   4. [인증서 경로 및 OCSP 검증] 수신자가 서명자의 X.509 인증서 체인 및 실시간 폐기 상태(OCSP) 확인
        │
   ▼
5. [수학적 일치 판정] 수신 문서의 SHA-256 해시값과 공개키 검증 서명값 일치 확정 (부인방지 성립)
```

#### 한줄 요약
- C14N 정규화 → 해시 추출 → HSM 개인키 서명 → X.509/OCSP 검증 → 수학적 서명 일치 판정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **RSA-PSS** vs **ECDSA/Ed25519** vs **ML-DSA (Post-Quantum Dilithium)**.

</details>

| 비교 항목 | RSA-PSS (RFC 8017) | ECDSA / Ed25519 (RFC 8032) | ML-DSA (NIST FIPS 204) |
|:---|:---|:---|:---|
| **수학적 기반** | **소인수분해 난제 + PSS 확률적 패딩**| **타원곡선 이산대수 (ECDLP / Curve25519)**| **모듈 격자 상의 학습 난제 (MLWE)** |
| **서명 크기** | **384 바이트 (RSA 3072비트 기준, 큼)** | **64 바이트 (256비트 기준, 극도로 작음)**| **2,420 바이트 (양자내성 구조, 큼)** |
| **서명/검증 속도** | 서명 연산 무거움, 검증 빠름 | **서명 및 검증 모두 극도로 빠름** | 고속 격자 다항식 연산 지원 |
| **난수(k) 오류 취약성**| 안전 (결정론적/확률적) | **위험 (RFC 6979 미적용 시 개인키 유출)**| 안전 (결정론적 서명 지원) |
| **양자 공격 저항성**| **취약 (Shor 알고리즘에 즉시 붕괴)** | **취약 (Shor 알고리즘에 즉시 붕괴)** | **영구적 안전 (양자 컴퓨터 내성)** |
| **주요 적용 분야** | 공인 전자문서, 코드 서명(Code Sign)| **TLS 1.3, 블록체인(비트코인/이더리움)** | **차세대 국가 기밀, 장기 보존 전자문서** |

#### 한줄 요약
- RSA-PSS는 레거시 호환, ECDSA/Ed25519는 고속 경량 표준, ML-DSA는 양자 공격 대비 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Sony PS3 Incident (ECDSA 난수 재사용 사고)**: 플레이스테이션 3 펌웨어 서명 시 난수 $k$를 고정값으로 사용하여 개인키가 대수적으로 역산 유출된 보안 사고.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ECDSA 서명 시 난수($k$) 재사용/편향으로 인한 **서명자의 개인키 즉시 유출 사고** | **`RFC 6979 결정론적(Deterministic) k 생성 또는 Ed25519(EdDSA)`** 강제 | 난수 결함 원천 제거 및 개인키 노출 확률 0% 달성 |
| 빌드 서버 침해 시 코드 서명키 탈취로 인한 **악성코드 위조 서명 배포** | 서명키를 **`FIPS 140-3 Level 3 HSM에 격리하고 CI/CD 다중 승인 서명`** 강제 | 서명키 비인가 반출 차단 및 공급망 위조 서명 완벽 차단 |
| 수년 후 인증서 만료로 과거 체결된 **전자계약서의 법적 부인방지 효력 상실** | **`RFC 3161 TSA 타임스탬프 및 LTV(PAdES-LTV) 검증 아티팩트 영구 임베딩`** | 인증서 만료 후에도 수십 년간 법적 증거력 보존 |
| 서명 대상 데이터의 인코딩 불일치로 인한 서명 검증 실패 | **서명 전 `정규화(Canonicalization) 표준 프로세스` 의무 적용** | 시스템 간 포맷 차이로 인한 검증 오작동 제거 |

#### 한줄 요약
- RFC 6979로 개인키 유출을 막고, HSM/다중 승인으로 공급망을 방어하며, TSA/LTV로 장기 증거력을 보증한다.

## Ⅶ. 결론

- 디지털 트랜스포메이션 환경에서 데이터의 진본성과 법적 효력을 보장하기 위해 **전자서명 아키텍처는 모든 신뢰 서비스(인증서, 블록체인, 코드 서명, 공공 전자문서)의 핵심 기틀**이며, 실무 구현 시 **결정론적 Ed25519/RSA-PSS 표준화, HSM 기반 개인키 무결점 보호, LTV 타임스탬프 결합, PQC(ML-DSA) 양자내성 서명 전환**을 선제 추진하여 지속 가능한 디지털 신뢰 생태계 완성

#### 한줄 요약
- 전자서명은 비대칭 개인키 서명과 해시 무결성 및 TSA 타임스탬프를 결합하여 법적 부인방지와 신원 인증을 실현하는 핵심 기술이다.
