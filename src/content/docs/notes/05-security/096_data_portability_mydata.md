## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **개인정보 전송요구권**: 정보주체가 법정 대상 정보를 본인이나 적격 수신자에게 보내도록 요구하는 권리이다.
- **마이데이터** 는 정보주체가 자신의 정보를 지정한 수신자에게 표준 방식으로 전송•활용하는 체계다.
- **스크래핑** 은 사용자 자격으로 화면 데이터를 자동 수집하는 방식이다.

</details>

- 정의/개념: **개인정보 전송요구권•마이데이터** 는 정보주체가 법정 범위의 개인정보를 본인이나 지정한 수신자에게 표준 방식으로 전송하도록 요구하는 권리와 서비스 체계
- 배경/필요성: 스크래핑의 **자격 공유•비표준 수집 위험**

#### 한줄 요약

- 비밀번호를 다른 서비스에 맡기지 않고 이용자가 항목과 받을 곳을 지정하면 보유 기관이 표준 형식으로 직접 보낸다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **자기결정권** 은 정보주체가 전송 목적•항목•수신자•주기•종료를 지정하는 권리다.
- **철회** 는 정보주체가 기존 개인정보 전송 요구를 취소하는 권리다.
- **기계 판독 형식** 은 프로그램이 자동으로 해석•처리할 수 있는 구조화된 데이터 형식이다.
- **적격 수신자** 는 법정 시설•기술•업무 요건을 갖춰 제3자 전송을 받을 수 있는 기관이다.
- **API(Application Programming Interface)** 는 서비스 기능과 데이터를 정해진 요청•응답 형식으로 제공하는 경계다.

</details>

- 정보주체 지정•철회의 **자기결정권**
- 표준 API•형식의 **상호운용성**
- 전송자•수신자의 **적격성•책임 분리**

#### 한줄 요약

- 이용자가 전송 목적•대상 정보•수신자•주기•종료 시점을 정하고 요구를 철회할 수 있어야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정보전송자** 는 정보주체의 요구에 따라 보유 정보를 지정 수신자에게 보내는 기관이다.
- **전문기관** 은 전송받은 개인정보를 정보주체를 대신해 관리•분석•활용하는 기관이다.
- **일반수신자** 는 전송받은 정보를 고유 업무의 진위 확인 등에 이용하는 기관이다.
- **전송 지원 플랫폼**: 정보주체의 요청을 전송자와 수신자에 연계하고 기관 적격성•요구•철회•중단 현황을 관리하는 기반이다.

</details>

```mermaid

```

| 구성요소 | 책임 |
|:---|:---|
| **정보주체** | 목적•항목•수신자•주기 **지정** |
| **정보전송자** | 법정 대상 추출•**표준 전송** |
| **전송 지원 플랫폼** | 요청 연계•**기관 현황 관리** |
| **전문기관•일반수신자** | **적격성•목적 내 이용** |
| **보안•이력 통제** | 본인 인증•암호화•**철회 기록** |

#### 한줄 요약

- 정보주체의 지정이 전송자와 적격 수신자를 연결하고 지원 플랫폼과 이력 통제가 전송•철회를 추적한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **본인 검증** 은 전송 요청자가 실제 정보주체인지 확인하는 절차다.
- **수신자 적격성 검증** 은 지정 수신자가 법정 자격•시설 기준을 갖췄는지 확인하는 절차다.
- **전송 이력** 은 요구 범위•전송 결과•거절•재시도 상태를 기록한 자료다.
- **철회 기록** 은 전송 요구의 취소•중단•종료 상태를 기록한 자료다.

</details>

```mermaid
sequenceDiagram
    participant U as 정보주체
    participant P as 지원 플랫폼
    participant H as 정보전송자
    participant R as 수신자
    U->>P: 목적•항목•수신자 지정
    P->>P: 1. 본인•수신자 적격성 검증
    P->>H: 검증된 전송 요구
    H->>H: 2. 법정 대상 정보 추출
    H->>H: 3. 표준 형식•암호화 구성
    H->>R: 암호화 전송 데이터
    P->>P: 4. 이력•철회•중단 기록
    R-->>U: 수신•처리 결과 제공
```

**동작 원리**

1. **본인•수신자 적격성 검증**: 요청자•기관•시설 기준 확인
2. **법정 대상 정보 추출**: 요구 범위에서 전송 예외 제외
3. **표준 형식•암호화 구성**: 기계 판독 데이터와 보호 채널 준비
4. **이력•철회•중단 기록**: 요구•거절•종료 상태 감사


#### 한줄 요약

- 본인과 수신자를 확인하고 법정 대상 정보만 안전하게 보내며 재시도•철회•중단 결과를 기록한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **열람** 은 개인정보를 화면이나 파일로 직접 확인하는 권리 행사 방식이다.
- **본인 전송** 은 구조화된 개인정보를 정보주체 자신의 저장소로 이동하는 방식이다.
- **제3자 전송** 은 구조화된 개인정보를 적격 수신자 서비스로 보내는 방식이다.

</details>

| 개인정보 이동 유형 | 열람•파일 제공 | 본인 전송 | 제3자 전송 |
|:---|:---|:---|:---|
| **적용 기준** | 사람이 **직접 확인** | **본인 저장소** 이동 | **지정 수신자** 서비스 |
| 핵심 특징 | **화면•파일 제공** | **본인에게 구조화 전송** | **적격 제3자 표준 전송** |
| **한계** | **반복•재사용 제약** | **개인 저장소 보호** | **적격성•목적 통제** |

#### 한줄 요약

- 열람은 사람이 확인하는 데 중심이 있고 전송은 시스템이 다시 활용할 수 있는 구조화된 정보 이동이라는 차이가 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **보호법 제35조의2** 는 본인•제3자 개인정보 전송요구권을 규정한다.
- **시행령 제42조의2~9** 는 전송자•수신자•대상 정보•절차•거절•중계를 구체화한다.
- **멱등키**: 같은 전송 요청이 재시도되더라도 수신 측에 중복 반영되지 않고 동일한 결과를 유지하게 하는 고유 요청 식별자이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **전송 대상•수신자** | **보호법 제35조의2 요건 검증** | **과다•부적격 전송** 방지 |
| **분야별 대상 정보** | **시행령•보호위 분야 고시 적용** | **현행 전송 범위** 일치 |
| **재시도•철회•감사** | **멱등키•암호화•전송이력 관리** | **중복•유출•분쟁** 방지 |

#### 한줄 요약

- 전송 API는 본인 확인과 법정 범위를 검증하고 표준 스키마와 멱등키를 사용해 재시도에도 중복 저장되지 않게 한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **전송 최소성** 은 정보주체가 지정한 법정 범위의 개인정보만 보내는 원칙이다.
- **전송 추적성** 은 전송 요구부터 철회•종료까지 처리 결과를 추적하는 성질이다.

</details>

- 범위•수신자 적격성•철회 상태 충족 시에만 **표준 전송 허용**

#### 한줄 요약

- 마이데이터의 핵심은 데이터를 많이 모으는 것이 아니라 정보주체가 지정한 법정 범위만 안전하고 추적 가능하게 이동하는 것이다.
