## 미리 알고가기

- **전송요구권**: 정보주체가 법정 대상 개인정보를 본인 또는 지정 수신자에게 보내도록 요구하는 권리
- **마이데이터**: 정보주체 요구에 따라 여러 기관의 본인정보를 안전하게 전송·통합하는 서비스 체계
- **정보전송자**: 법령에 따라 개인정보를 보유하고 전송 요구를 이행하는 기관·사업자
- **개인정보관리 전문기관**: 전송받은 개인정보를 정보주체 대신 안전하게 관리·활용하도록 지정된 기관
- **일반수신자**: 정보주체가 제3자 전송 대상으로 지정한 전문기관 외의 적격 수신자
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: '에이피아이'로 읽고 기관 간 전송 요청·데이터·결과를 교환하는 표준 연결 규칙
- **기계 판독 형식**: 프로그램이 필드와 값을 자동 해석할 수 있는 구조화된 데이터 형식
- **멱등성**: 같은 전송 요청이 반복돼도 데이터가 중복 반영되지 않고 같은 결과가 유지되는 성질
- **스크래핑**: 사용자 자격증명으로 화면에 접속해 표시 데이터를 자동 수집하는 방식
- **전 분야 마이데이터 시행**: 2025년 3월 13일 의료·통신을 시작으로 법정 10개 분야를 단계적으로 확대하는 제도

## Ⅰ. 개요

- 정의/개념: 정보주체가 법정 대상 개인정보의 **본인·지정 수신자 전송을 요구하는 권리**
- **배경/필요성**: 화면 스크래핑의 **자격 증명 공유·비표준 수집·통제권 약화 해소**

### 쉽게 이해하기 (학습용)

- 화면을 긁어 비밀번호를 맡기는 방식 대신, 이용자가 항목과 받을 곳을 지정하면 보유 기관이 표준 형식으로 안전하게 보내는 구조임.

## Ⅱ. 특징

- **정보주체 지정·신원·철회**로 목적·항목·수신자를 통제한다.
- **표준 API·기계 판독 형식**으로 전송·재시도·이력을 관리한다.
- **전송자·전문기관·일반수신자**의 적격성·보호 책임을 구분한다.

### 쉽게 이해하기 (학습용)

- 이용자가 전송 대상·항목·기간을 정하고 언제든 철회할 수 있어야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 정보주체 | **목적·항목·수신자 지정·철회** |
| 정보전송자 | **법정 대상 추출·표준 전송** |
| 수신기관 | **적격성 확인·목적 내 이용** |
| 지원 플랫폼 | **요청 연계·전송 이력 관리** |
| 보안 통제 | **신원 인증·구간 보호** |

```text
[정보주체] ─목적·항목·수신자 지정─> [정보전송자]
    ↑                                      │
    └──────── 전송 이력·철회 ──────────────┤
                                           ↓ 표준 API
                         [본인 저장소 / 전문기관 / 일반수신자]
```

### 쉽게 이해하기 (학습용)

- 정보주체의 지정이 전송자와 수신자를 잇고 이력과 철회가 전 과정을 통제함

## Ⅳ. 원리 및 절차 흐름도

```text
지정확인
↓
신원인증
↓
대상추출
↓
암호전송
↓
이력관리
```

| 절차 | 설명 |
|:---|:---|
| 지정확인 | 정보주체가 목적·항목·수신자 설정함 |
| 신원인증 | 요청자 신원 및 수신자 적격성 검증함 |
| 대상추출 | 법정 대상 및 예외 기준에 따라 준비함 |
| 암호전송 | 표준 형식 및 안전한 채널로 전달함 |
| 이력관리 | 전송 이력 기록 및 철회·삭제 반영함 |

### 쉽게 이해하기 (학습용)

- 본인과 수신자를 확인한 뒤 대상 정보만 안전하게 보내고 결과를 기록함

## Ⅴ. 종류 및 비교

| 개인정보 제공 방식 | 열람·파일 제공 | 본인 전송 | 제3자 전송 |
|:---|:---|:---|:---|
| 적용 기준 | 사람이 직접 확인 | 본인 저장소로 이동 | 지정 수신자 서비스 이용 |
| 핵심 특징 | 화면·파일 제공 | 본인에게 구조화 전송 | 제3자에게 표준 전송 |
| 한계 | 반복 작업·재사용 제약 | 본인 저장소 보호 필요 | 수신자 적격성·목적 통제 |

> 요약: 범위·주체 검증을 거쳐 데이터를 암호화 전송함

### 쉽게 이해하기 (학습용)

- 파일 열람보다 표준 전송은 시스템이 읽고 처리할 수 있다는 차이가 있음

## Ⅵ. 실무 사례

1. 마이데이터 전송 API의 **표준 스키마·멱등성 보장**

### 쉽게 이해하기 (학습용)

- 정보 제공자는 본인 확인과 동의 범위를 검증하고 표준 스키마로 데이터를 전송하며, 재시도에도 중복 저장되지 않게 멱등성을 보장한다.

## Ⅶ. 결론

- 개인 데이터의 폐쇄적 보관과 비표준 이동을 극복하기 위해 정보주체 권한·전송 범위·수신자·표준 API·철회를 검토하여, 안전한 데이터 이동에 전송요구권과 마이데이터를 활용해야 한다.

### 쉽게 이해하기 (학습용)

- 비밀번호를 다른 서비스에 맡기는 스크래핑보다 법정 대상 정보를 표준 API로 직접 보내는 경로가 안전함
