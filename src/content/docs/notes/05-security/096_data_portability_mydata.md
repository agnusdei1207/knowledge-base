## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **개인정보 전송요구권 (Data Portability Right)**: 정보주체가 거대 플랫폼 기업에 인질로 잡혀있는 자신의 법정 대상 데이터를 본인 스마트폰으로 직접 내려받거나, 내가 원하는 적격 제3자 핀테크 수신자 플랫폼으로 즉시 쏴달라고 당당히 강제 요구할 수 있는 핵심 데이터 주권 권리이다.
- **마이데이터 (MyData 생태계)**: 과거 기업 중심의 데이터 독점 구조를 깨부수고, 정보주체가 자기 정보의 100% 통제권을 쥐고 본인이 원하는 수신자에게 API 표준 방식으로 전송 지시·융합·활용하는 사용자 중심의 거대한 정보 주권 생태계 팩트이다.
- **스크래핑 (Screen Scraping)**: 마이데이터 도입 전, 핀테크 앱이 내 은행 아이디와 비밀번호를 통째로 넘겨받아 나인 척 로그인한 뒤 화면의 HTML 텍스트를 무식하게 긁어가는 방식으로, 아이디 탈취 위험과 무단 접속을 유발하던 구시대적 위험천만 수집 방식 팩트이다.

</details>

- 정의: 정보주체의 강력한 지시에 따라, 과거 **스크래핑** 보안 위협을 폐기하고, **개인정보 전송요구권** 안전한 API 표준 전송으로 즉각 지원·통제하는 **사용자 중심 데이터 유통 체계**이다.
- 배경: 과거 공인인증서와 비밀번호를 통째로 핀테크 앱에 맡기는 **스크래핑** 방식은 최악의 '사용자 자격 무단 공유'와 '비표준 화면 해킹 수집'이라는 심각한 보안 침해 위험을 양산했기 때문이다.

#### 한줄 요약

- 내 비밀번호를 남의 앱에 통째로 맡기는 위험을 폐기하고, 이용자가 전송 항목과 받을 곳을 직접 지정 통제하면 데이터 보유 기관이 안전한 API 표준 형식으로 직접 쏴주는 데이터 주권 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **자기결정권 (Self-Determination Right)**: 기업 맘대로가 아니라, 정보주체 본인이 직접 내 데이터의 '어떤 항목(범위)'을, '누구(수신자)'에게, '언제(기간/주기)' 전송할지 칼같이 지정하고 통제하는 최고 주권 권리이다.
- **철회 (Revocation)**: 한 번 전송 동의를 했더라도, 맘에 안 들면 그 즉시 기존 개인정보 전송 요구를 취소 셧다운하여 데이터 파이프라인을 끊어버리는 막강한 권리이다.
- **기계 판독 형식 (Machine-Readable Format)**: 사람이 눈으로 읽는 엑셀/PDF가 아니라, 수신 측 서버 컴퓨터 프로그램이 자동으로 즉각 파싱·해석·처리할 수 있는 JSON/XML 같은 구조화된 데이터 표준 포맷 팩트이다.
- **적격 수신자 (Qualified Recipient)**: 아무 스타트업이나 데이터를 받을 수 있는 것이 아니라, 국가가 요구하는 엄격한 물리적 시설·망분리 보안 기술·업무 요건 라이선스를 까다롭게 심사 통과해 제3자 전송을 받을 자격을 획득한 인가 기관 팩트이다.
- **API (Application Programming Interface)**: 종이 서류나 화면 캡처가 아니라, 은행과 핀테크 서비스 서버끼리 기능과 데이터를 정해진 디지털 요청·응답 규격으로 1초 만에 안전하게 자동 펌핑해 주는 통신 경계망 팩트이다.

</details>

- **절대적 자기결정권 및 철회 통제**: 정보주체의 **자기결정권** 및 즉각적 **철회** 발동을 통해, 데이터 전송 목적·허용 범위·유지 기간을 100% 본인이 통제하는 원칙이다.
- **API 기반 기계 판독 데이터 펌핑**: 더 이상 엉성한 화면 스크래핑에 의존하지 않고, **API** 망과 JSON **기계 판독 형식** 통해 시스템 간 방대한 데이터를 1초 만에 쏟아붓는 전송을 지원한다.
- **적격 수신자 철벽 제한 및 책임 분리**: 아무에게나 내어주지 않고 국가가 인가한 **적격 수신자** 여부를 철저히 검증하며, 유출 시 쏴준 '전송자'와 넘겨받은 '수신자'의 연대 책임을 명확히 칼 분리 통제한다.

#### 한줄 요약

- 이용자가 절대 통제권을 쥐고 전송 목적·대상 데이터·수신자·주기·종료 시점을 정하고 철회할 수 있어야 하며, 낡은 스크래핑 대신 API와 기계 판독 형식으로 적격 수신자에게만 쏴주는 구조이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정보주체 (Data Subject)**: "내 국민은행 계좌 내역을 토스로 보내!"라고 명령하며, 자신의 개인정보 전송 범위와 수신자를 지정하는 절대 권한의 개인이다.
- **정보전송자 (Data Sender)**: 정보주체의 지상 명령에 따라 자신들이 독점하던 알짜배기 보유 정보를 강제로 지정 수신자(토스 등)에게 울며 겨자 먹기로 펌핑해 보내야 하는 은행/통신사 등 기존 독점 기관 팩트이다.
- **개인정보관리 전문기관 (PIMS / 전문기관)**: 전송받은 엄청난 양의 개인정보를 정보주체를 대신해 안전하게 통합 관리·분석·활용 대행해 주는 고도의 보안 라이선스를 취득한 마이데이터 사업자 팩트이다.
- **마이데이터 종합지원 플랫폼 (MyData Support Platform)**: 정보주체의 전송 요구 트래픽을 수많은 전송자와 수신자 사이에 중앙 연계 라우팅해주고, 수신 기관의 적격성 심사 이력·전송 요구·철회·중단 현황을 국가 차원에서 중앙 감시 통제하는 컨트롤 타워 기반이다.

</details>

```text
[마이데이터 전송 권리 요구 및 API 연계 유통 통제 구조]

├─ [1. 절대 요구 주체 경계]
│    └─ [정보주체] (내 데이터 내놔 전송 명령 하달)
│
├─ [2. 중앙 연계 및 적격성 통제 경계]
│    └─ [마이데이터 종합지원 플랫폼] (API 중계 라우팅 및 자격 심사 통제)
│
├─ [3. 실제 데이터 파이프라인 전송 관계]
│    ├─ [정보전송자] (데이터 독점 해제 및 의무 송신)
│    └─ [전문기관 / 적격 일반수신자] (데이터 수신 및 융합 활용)
│
└─ [4. 전 과정 공통 지배 통제]
     └─ [통합 보안 및 영구 이력 통제] (본인 인증, API 암호화, 철회 로깅)
```

| 구성요소 | 핵심 보안 통제 및 책임 |
|:---|:---|
| **정보주체** | **정보주체** 전송 목적, 넘길 항목, 받을 수신자, 유지 주기 절대 지정 및 권리 행사 |
| **정보전송자** | **정보전송자** 사용자 명령 즉시 법정 데이터 대상 추출 및 API 표준 포맷 전송 이무 집행 |
| **종합지원 플랫폼** | **전송 지원 플랫폼** 수만 개 요청 연계 라우팅 및 타겟 기관 무자격 현황 중앙 모니터링 관리 |
| **전문기관 및 일반수신자** | 국가 허가를 받은 **전문기관** 및 **일반수신자** 적격성 유지 및 허용 목적 내 철저한 제한적 이용 |
| **통합 보안 및 이력 통제** | mTLS 상호 인증, 엔드투엔드 구간 암호화 적용 및 언제든 끊을 수 있는 100% **철회** 증적 기록 |

#### 한줄 요약

- 정보주체의 명령 지정이 정보전송자와 적격 수신자를 데이터 파이프라인으로 1:1 연결하고, 국가 지원 플랫폼과 API 이력 통제가 전체 전송·철회 흐름을 라우팅 추적하는 생태계이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **본인 철저한 검증 (Identity Verification)**: "토스로 보내"라고 요청한 놈이 해커가 아니라 실제 계좌 주인인 정보주체 본인이 맞는지 CI/DI, 생체 인증 등으로 확실히 컷 확인하는 철벽 절차이다.
- **수신자 적격성 검증 (Recipient Eligibility Check)**: 정보주체가 지정한 수신자 기업이, 망분리 엉망인 유령 회사가 아니라 국가 법정 자격·보안 시설 기준을 완벽히 갖춘 마이데이터 라이선스 기관인지 확인하는 방어 절차이다.
- **전송 영구 이력 (Transmission Audit Trail)**: 요구 범위, 전송 성공/실패 결과, 비정상 거절 건수, 오류 재시도 상태를 빼도 박도 못하게 로깅 기록한 감사 자료이다.
- **본인•수신자 적격성 검증 단계**: 요청자 신원과 지정 수신자의 법정 자격·보안 요건을 심사 통과시키는 진입 단계이다.
- **법정 대상 정보 칼 추출 단계**: 고객이 털어가라고 한 전송 요구 범위 내에서 법정 필수 대상 정보만 칼같이 선별하고, 영업비밀 예외 항목은 철저히 필터링 제외하는 단계이다.
- **표준 형식 및 구간 암호화 구성 단계**: 긁어가기 쉬운 기계 판독 데이터(JSON)로 포맷을 통일하고 mTLS 암호화 전송 채널을 파이프라인으로 준비하는 단계이다.
- **이력•철회•중단 로깅 기록 단계**: 모든 요구·전송 집행·거절·취소·종료 상태를 나중의 분쟁 시 감사 가능하게 블록체인급으로 남기는 증거 단계이다.

</details>

```text
[정보주체의 목적 확정, 전송 항목, 적격 수신자 지정 지시 명령 하달]
                  |
                  v
1. 요청자 본인 생체/통합 인증 및 타겟 수신자의 법정 라이선스 적격성 철저한 검증
                  |
                  v
2. 전송 요구 범위 내 법정 대상 데이터 칼 추출 및 영업비밀 예외 필터링 차단
                  |
                  v
3. JSON 기계 판독 표준 형식 변환 패킹 및 mTLS API 암호화 파이프라인 채널 구성
                  |
             (전송 API 펌핑)
                  |
                  v
4. 전송 집행 성공 여부, 즉각 철회, 비상 중단 로그 등 불변 이력 증적 기록
                  |
                  v
       [적격 수신자의 데이터 수신 및 융합 처리 결과 도출]
```

### 동작 원리

1. 본인·수신자 적격 검증: 요청자의 CI 본인 확인과 수신 회사 라이선스 자격을 철통 확인한다.
2. 대상 정보 칼 추출: 요구 범위에서만 뽑고, 전송 의무가 없는 예외 정보는 방어선으로 제외한다.
3. 표준 형식·암호화 채널 구성: 기계 판독용 데이터로 랩핑하고 API 구간 암호화(mTLS)를 세팅한다.
4. 이력·철회·중단 불변 기록: 누가 언제 뭘 요구하고 거절·종료했는지 낱낱이 로깅 감사 증적을 남긴다.

#### 한줄 요약

- 철저한 본인 인증과 수신자 자격을 확인한 뒤, 법정 대상 정보만 뽑아 안전한 API로 보내며, 모든 전송 재시도·철회·중단 결과를 블록체인급으로 기록한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **과거 단순 열람 (Access/View)**: 은행 앱에 접속해 내 거래 내역을 단순 텍스트 화면이나 PDF 파일로 눈으로 훑어보고 마는 수동적 권리 행사 방식이다.
- **본인 전송 (Portability to Self)**: 구조화된 엑셀/CSV 개인정보 파일을 정보주체 자신의 개인 스마트폰 저장소 클라우드로 쏙 빼내어 다운로드 이동 보관하는 방식이다.
- **제3자 전송 (Portability to Third Party)**: 다운로드 없이, 은행에 있는 내 데이터를 핀테크 등 적격 수신자 서버 서비스로 보이지 않게 다이렉트 펌핑해 보내는 핵심 마이데이터 방식이다.

</details>

| 정보주체 데이터 이동 통제 권리 유형 | **단순 화면 열람 및 파일 제공 (Access)** | **스마트폰 본인 전송 (To Self)** | **다이렉트 제3자 전송 (To Third Party)** |
|:---|:---|:---|:---|
| 데이터 이동 적용 패러다임 | 사용자의 일회성 시각적 **열람** | 저장소 다운로드 **본인 전송** | 적격 핀테크로의 **제3자 전송** |
| 핵심 기술적 전송 특징 | 눈으로 읽는 단순 텍스트/PDF 화면 제공 | 본인 기기로 기계 판독 구조화 파일(CSV) 통 다운로드 전송 | 사용자 폰을 거치지 않고 타사로 API 다이렉트 표준 전송 펌핑 |
| 치명적 한계점 및 보안 위험 | 시스템 연동 반복 및 핀테크 앱 재사용 극도 제약 | 개인이 스마트폰 잃어버리거나 해킹 시 대규모 유출 폭탄 리스크 | 넘겨받은 수신자가 딴맘 안 먹게 적격성 검증 및 목적 외 이용 통제 난제 |

#### 한줄 요약

- 단순 '열람'은 인간이 눈으로 확인하는 1차원적 수준이며, 진정한 마이데이터 '전송'은 다른 IT 시스템이 1초 만에 파싱해 재활용할 수 있는 기계 판독 가능한 구조화된 정보의 다이렉트 파이프라인 이동이라는 본질적 차이가 있다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **보호법 제35조의2 (전송요구권 핵심 조항)**: 단순 열람을 넘어 본인 스마트폰 또는 적격 제3자에게 개인정보를 펌핑해 전송하라고 요구할 수 있는 마이데이터 빅뱅의 근간을 규정한 조항이다.
- **시행령 제42조의2~9 (마이데이터 상세 가이드)**: 두루뭉술한 법을 쪼개어 누가(전송자), 누구에게(수신자), 무엇을(대상 정보), 어떻게(절차·거절·중계) 보내야 하는지를 실무적으로 꽉 짜여진 룰로 구체화한 타이트한 조항 묶음이다.
- **멱등키 (Idempotency Key)**: 네트워크 통신 단절로 같은 전송 요청이 10번 급격히 재시도 폭주하더라도, 수신 측 DB에 중복으로 데이터가 10개 쌓이지 않고 딱 1회 처리된 것과 완벽히 동일한 상태 결과를 유지하게 강력히 통제하는 고유 API 요청 식별자 팩트이다.

</details>

| 서비스 장애/보안 위협 사고 | 근본 원인 취약점 분석 | 최정예 실무 방어 대책 및 해결방안 | 기대 철벽 통제 효과 |

#### 한줄 요약

- 마이데이터 전송 API 망은 살벌한 본인 확인과 법정 범위 커트 검증을 최전선에 걸고, JSON 표준 스키마와 멱등키(Idempotency Key) 아키텍처를 도입해 수백 번의 통신 장애 재시도 트래픽에도 DB에 중복 꼬임이 절대 저장되지 않게 철벽 통제한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **전송 최소성 원칙 (Data Minimization in Portability)**: 무식하게 DB 전체를 덤프 떠서 퍼주는 것이 아니라, 오직 정보주체가 칼같이 핀셋 지정한 법정 범위 한도 내의 개인정보 레코드만 정확히 끊어서 보내는 무관용 전송 원칙이다.
- **무결 전송 추적성 (Transmission Traceability)**: 사용자가 버튼을 누른 전송 요구 시작점부터 펌핑 완료, 그리고 나중의 철회·완전 셧다운 종료 시점까지 모든 트랜잭션 처리 결과 족적을 블록체인처럼 끊기지 않게 100% 연결 추적 입증해 내는 무결 성질이다.

</details>

- 마이데이터는 많이 긁어모으는 게 장땡이 아니므로, 철저한 **전송 최소성** 원칙으로 범위를 핀셋 제한하고 적격 핀테크 수신자와 철회 상태를 실시간 확인하며, 불변의 **전송 추적성** 로깅을 유지할 때만 표준 API 펌핑 전송을 집행하는 것이 필수이다.

#### 한줄 요약

- 마이데이터 혁명의 진정한 핵심은 데이터를 무작정 거대하게 긁어모으는 탐욕이 아니라, 오로지 정보주체가 칼같이 지정 통제한 법정 범위 한계 내에서만 안전하고 영구 추적 가능하게 API 파이프라인으로 이동시키는 통제 구현 필수.
