## 미리 알고가기

- **전송요구권**: 정보주체가 법정 대상 개인정보를 본인 또는 지정 수신자에게 보내도록 요구하는 권리
- **마이데이터**: 정보주체 요구에 따라 여러 기관의 본인정보를 안전하게 전송·통합하는 서비스 체계
- **정보전송자**: 법령에 따라 개인정보를 보유하고 전송 요구를 이행하는 기관·사업자
- **개인정보관리 전문기관**: 전송받은 개인정보를 정보주체 대신 안전하게 관리·활용하도록 지정된 기관
- **일반수신자**: 정보주체가 제3자 전송 대상으로 지정한 전문기관 외의 적격 수신자
- **API (Application Programming Interface)**: 기관 사이에서 전송 요청·데이터·결과를 교환하는 연결 규칙
- **기계 판독 형식**: 프로그램이 필드와 값을 자동 해석할 수 있는 구조화된 데이터 형식
- **멱등성**: 같은 전송 요청이 반복돼도 데이터가 중복 반영되지 않고 같은 결과가 유지되는 성질
- **스크래핑**: 사용자 자격증명으로 화면에 접속해 표시 데이터를 자동 수집하는 방식
- **API 읽기와 표기**: “에이피아이”로 읽으며 Application·Programming·Interface의 머리글자를 묶어 기관 간 연결 규칙을 나타냄

## Ⅰ. 개요

- **정의/개념**: 지정 개인정보의 구조화 전송 권리·체계
- **배경/필요성**: 개인 주도의 안전한 데이터 이동 필요

### 쉽게 이해하기 (학습용)

- 화면을 긁어 비밀번호를 맡기는 방식 대신, 이용자가 항목과 받을 곳을 지정하면 보유 기관이 표준 형식으로 안전하게 보내는 구조임.

## Ⅱ. 특징

- 법령에 따라 적용 분야·전송 대상을 확대한다.
- 정보주체가 전송 목적·범위를 통제·철회한다.
- 표준 API가 기계 판독 자료를 자동 연계한다.
- 수신 자료의 목적·전송 이력을 관리한다.

### 쉽게 이해하기 (학습용)

- 이용자가 전송 대상·항목·기간을 정하고 언제든 철회할 수 있어야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 정보주체 | 전송 요구·철회 및 이력 확인 |
| 정보전송자 | 대상 정보 추출 및 표준 전송 |
| 수신기관 | 데이터 수신 및 목적별 활용 |
| 지원플랫폼 | 요청 연계 및 이력 관리 |
| 보안계층 | 신원 인증 및 전송 보호 |

```text
[정보주체] ─목적·항목·수신자 지정─> [정보전송자]
    ↑                                      │
    └──────── 전송 이력·철회 ──────────────┤
                                           ↓ 표준 API
                         [본인 저장소 / 전문기관 / 일반수신자]
```

### 쉽게 이해하기 (학습용)

- 정보주체의 지정이 전송자와 수신자를 잇고 이력과 철회가 전 과정을 통제함

## Ⅳ. 원리 및 절차 흐름도

```text
지정확인
↓
신원인증
↓
대상추출
↓
암호전송
↓
이력관리
```

| 절차 | 설명 |
|:---|:---|
| 지정확인 | 정보주체가 목적·항목·수신자 설정함 |
| 신원인증 | 요청자 신원 및 수신자 적격성 검증함 |
| 대상추출 | 법정 대상 및 예외 기준에 따라 준비함 |
| 암호전송 | 표준 형식 및 안전한 채널로 전달함 |
| 이력관리 | 전송 이력 기록 및 철회·삭제 반영함 |

### 쉽게 이해하기 (학습용)

- 본인과 수신자를 확인한 뒤 대상 정보만 안전하게 보내고 결과를 기록함

## Ⅴ. 종류 및 비교

| 적용 기준 | 열람·파일제공 | 본인전송 | 제3자전송 |
|:---|:---|:---|:---|
| 핵심 특징 | 사람이 읽는 화면·파일 제공 | 본인 또는 본인 도구로 구조화 전송 | 지정 수신자에게 표준 방식으로 전송 |
| 적용 기준 | 정보 내용을 확인·보관할 때 | 본인이 다른 서비스로 직접 옮길 때 | 전문기관·일반수신자의 서비스를 이용할 때 |
| 주요 위험 | 반복 수작업·기계 활용 어려움 | 저장 도구 분실·대리인 오용 | 수신자 적격성·목적 외 이용·철회 누락 |

> 요약: 범위·주체 검증을 거쳐 데이터를 암호화 전송함

### 쉽게 이해하기 (학습용)

- 파일 열람보다 표준 전송은 시스템이 읽고 처리할 수 있다는 차이가 있음

## Ⅵ. 실무 사례

- 마이데이터 API: 대상 스키마 매핑 및 멱등성 보장
- 수신 서비스: 목적별 최소 항목 및 철회 시 즉시 파기

### 쉽게 이해하기 (학습용)

- 전송 API는 기관별 필드를 표준 스키마에 맞추고 재시도해도 중복 저장되지 않게 함
- 수신 서비스는 목적에 필요한 항목만 받고 철회·기간 종료 때 삭제 상태를 이력에 남김

## Ⅶ. 결론

- 표준 전송과 신원·이력·철회를 연결함

### 쉽게 이해하기 (학습용)

- 비밀번호를 다른 서비스에 맡기는 스크래핑보다 법정 대상 정보를 표준 API로 직접 보내는 경로가 안전함
