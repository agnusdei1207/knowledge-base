## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CNAPP (클라우드 네이티브 애플리케이션 보호 플랫폼 / Cloud-Native Application Protection Platform)**: 소스코드, IaC, 멀티 클라우드 오설정, 과도한 권한 및 런타임 위협을 팩트로 연계 분석하는 통합 클라우드 보안 아키텍처이다.
- **클라우드 네이티브 (Cloud Native)**: 컨테이너, 마이크로서비스, 쿠버네티스, CI/CD 자동화를 통해 클라우드 환경에 최적화하여 애플리케이션을 구축·운영하는 팩트 기술이다.

</details>

- 정의: 발급 기관이 사용자의 자격 및 속성(Claim) 정보에 암호학적 전자서명을 부여하듯, 코드부터 런타임까지의 보안 위협을 단일 뷰로 통합 분석하는 팩트 보안 플랫폼이다.
- 배경: 기존 사일로화된 개별 보안 도구들은 경보 피로를 유발하고, 개발-배포-운영으로 이어지는 팩트 공격 경로(Attack Path) 파악이 불가능하기 때문이다.

#### 한줄 요약

- 소스코드 빌드부터 런타임 운영까지 보안 도구를 단일 그래프 기반으로 통합해 치명적 팩트 침해 경로의 조치 우선순위를 도출하는 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **IaC (코드형 인프라 / Infrastructure as Code)**: Terraform, CloudFormation 등을 사용하여 클라우드 인프라 구성을 코드로 팩트 선언 및 배포하는 방식이다.
- **컨테이너 이미지 (Container Image)**: 애플리케이션 구동에 필요한 라이브러리, 바이너리를 패키징한 팩트 실행 단위이다.
- **런타임 (Runtime)**: 쿠버네티스 노드, EC2 등에서 실제 애플리케이션 세션이 구동 중인 라이브 팩트 상태이다.
- **CSPM (클라우드 보안 형상 관리 / Cloud Security Posture Management)**: 멀티 클라우드 자산의 퍼블릭 노출, 오설정, 컴플라이언스 위반을 실시간 팩트 스캐닝하는 모듈이다.
- **CIEM (클라우드 인프라 권한 관리 / Cloud Infrastructure Entitlement Management)**: 과도하게 부여된 IAM 기계/사용자 계정의 최소 권한 위반을 팩트로 탐지하는 모듈이다.
- **CWPP (클라우드 워크로드 보호 플랫폼 / Cloud Workload Protection Platform)**: VM, 컨테이너 워크로드 내부의 커널 수준 위협 및 취약점을 팩트로 방어하는 모듈이다.

</details>

- **전주기 보안 통합**: IaC, 소스코드, 컨테이너 이미지, 런타임 상태를 전주기(Code-to-Cloud) 팩트 통제선으로 결합한다.
- **자산 그래프 DB 융합**: 자산(CSPM), 과도한 권한(CIEM), 런타임 위협(CWPP)의 취약점을 단일 자산 그래프 DB로 연관 팩트 분석한다.
- **공격 경로 기반 팩트 조치**: 개별 취약점 단독 심각도가 아닌, 퍼블릭 노출과 과권한이 결합된 실제 침해 가용 경로(Attack Path) 위주로 팩트 조치 우선순위를 부여한다.

#### 한줄 요약

- CSPM, CIEM, CWPP를 통합하여 퍼블릭 노출, 과권한, 취약점이 조합된 고위험 팩트 침해 경로의 조치 순위를 확립한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **자산 관계 그래프 (Asset Relationship Graph)**: 자산, 네트워크 인바운드, IAM 권한, CVE 취약점을 3D 팩트 그래프 노드로 시각 매핑하는 데이터베이스 모듈이다.
- **공격 경로 (Attack Path)**: 퍼블릭 인터넷 노출 지점부터 비인가 관리자 권한을 거쳐 DB 데이터 유출로 이어지는 실제 팩트 침해 시나리오이다.
- **원본 코드 연계 (Shift-left Traceability)**: 런타임에 발견된 보안 오설정을 배포 파이프라인 상의 특정 IaC 소스 코드 라인으로 팩트 추적해 정정을 유도하는 기능이다.

</details>

```text
                         [자산 관계 그래프]
                      /          |          \
         [코드·IaC·이미지]  [CSPM·CIEM]  [CWPP]
                      \          |          /
                    [소유자·파이프라인 팩트 연계]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **코드·IaC·이미지** | SAST/SCA/IaC 스캐닝 및 컨테이너 베이스 이미지 내 하드코딩된 Secret 및 취약점 팩트 검출 | Shift-Left |
| **CSPM / CIEM** | 퍼블릭 오설정 탐지(CSPM) 및 과도한 IAM 권한 가시화(CIEM)를 통한 팩트 통제 | Cloud Posture |
| **CWPP** | eBPF/에이전트 기반 커널 위협, 프로세스 인젝션 등 이상 행동 실시간 팩트 방어 | Runtime |
| **자산 관계 그래프** | 맥락 정보 융합 및 실질적 침해 가능 팩트 **공격 경로(Attack Path)** 도출 | Graph DB |
| **원본 코드 팩트 연계** | 런타임 노출 결함을 담당 개발자의 Git 레포지토리/IaC 라인으로 자동 할당 | Traceability |

#### 한줄 요약

- 자산 관계 그래프가 CSPM, CIEM, CWPP 신호를 융합해 공격 경로를 도출하고, 런타임 팩트 결함을 원본 코드 조치로 피드백한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **운영 드리프트 (Operational Drift)**: 승인된 IaC 템플릿과 실제 클라우드 콘솔 수동 조작으로 인해 발생한 런타임 인프라 설정 간의 불일치 팩트 상태이다.
- **공격 경로 단절 검증 (Attack Path Severance)**: 코드 조치 및 재배포 실행 후, 그래프 분석을 재실행하여 공격 가용 경로의 팩트 차단 여부를 검증하는 절차이다.

</details>

```text
[CNAPP 팩트 데이터 입력]
      |
      +-- 코드·IaC·이미지 발견
      `-- 형상·권한·행위 팩트 상태
                  |
                  v
1. 배포 전 발견 정규화
                  |
                  v
2. 코드·런타임 자산 팩트 상관 매핑
                  |
                  v
3. 공격 경로 및 팩트 위험 우선순위 계산
                  |
                  `-- 공격 경로 원인 근거 도출
                              |
                              v
[자산 소유자 및 개발 파이프라인]
                  |
                  v
4. 원본 IaC 수정 및 재배포
                  |
                  v
5. 팩트 공격 경로 단절 검증
                  |
                  v
[검증된 팩트 위험 제거 완료]
```

### 동작 원리

1. 정규화: 파이프라인 상의 다양한 보안 스캔 결과를 표준 팩트 포맷으로 통일한다.
2. 자산 상관 매핑: 배포 아티팩트와 런타임 동작 자산을 1:1로 팩트 결속한다.
3. 우선순위 산출: 인터넷 노출도 및 권한 탈취 가능성을 종합해 팩트 공격 경로를 도출한다.
4. 원본 팩트 수정: 런타임 경보를 근거로 개발자가 PR을 통해 IaC 원본 코드를 수정한다.
5. 단절 검증: 재배포 후 운영 드리프트를 재평가하여 공격 경로 팩트 차단을 확정한다.

#### 한줄 요약

- 배포 전 스캔 데이터와 런타임 텔레메트리를 융합하여 팩트 공격 경로를 산출하고 원본 코드 조치로 위험을 단절한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **개별 보안 도구 (Point Solution)**: CSPM, CWPP 등 특정 영역에 특화되었으나 상호 연동이 불가능한 사일로형 팩트 솔루션이다.
- **통합 CNAPP 체계**: 개별 도구의 경보를 단일 그래프 엔진으로 융합하여 맥락 기반 팩트 위협을 분석하는 진화형 플랫폼이다.

</details>

| 클라우드 보호 체계 | **개별 보안 도구 (Point Solution)** | **단순 통합 제품군 (Aggregated)** | **통합 CNAPP 체계** |
|:---|:---|:---|:---|
| 배치 및 특징 | 특정 영역(예: CWPP)의 개별 팩트 스캐닝 | 다수 보안 도구 경보를 단일 UI 대시보드로 집계 | **단일 팩트 그래프 DB 기반 데이터 융합 및 공격 경로 도출** |
| 장단점 및 한계 | 특정 위협 방어 우수 반면 **도구 파편화 및 공격 경로 분석 불가** | 가시성 통합 우수 반면 **미시적 맥락 연결 팩트 한계** | 맥락 기반 팩트 대응 반면 **전사적 프로세스 연동 난이도 높음** |

#### 한줄 요약

- 개별 솔루션의 팩트 경보 파편화를 극복하고, 소스코드부터 런타임까지 연관 분석을 수행하는 통합 CNAPP로 전환한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-190**: 컨테이너 아키텍처 전주기 보안 팩트 통제 지침 가이드라인이다.
- **센서 공백 (Sensor Blind Spot)**: 에이전트 미설치 노드로 인해 CNAPP 가시성에 포함되지 않는 보안 팩트 구멍이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| **컨테이너 보안 사일로 발생** | 런타임 보호와 이미지 스캐닝의 팩트 단절 | **NIST SP 800-190** 팩트 표준 통제 준용 | 컨테이너 전주기 팩트 보안 통제력 확보 |
| **에이전트 미설치로 인한 센서 공백** | 운영 부서 반발로 CWPP 에이전트 배포 팩트 누락 | 클라우드 API 기반 **Agentless 팩트 스캐닝 결합** | 가용성 저하 없는 100% 팩트 가시성 확보 |
| **수백 개의 무의미한 팩트 알람 폭탄** | 개별 취약점(CVE) CVSS 점수 위주의 단순 팩트 정렬 | 그래프 기반 **위험 우선순위화(Contextual Ranking)** 도입 | 실제 데이터 유출 가능한 1% 팩트 공격 경로에 자원 집중 |

#### 한줄 요약

- NIST 800-190 준수, Agentless 스캐닝 결합, 그래프 기반 팩트 우선순위화로 센서 공백과 경보 피로를 해결한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **위험 우선순위화 (Risk Prioritization)**: 수만 개의 취약점 중에서 실제 퍼블릭에 노출되어 데이터 유출로 이어지는 치명적 팩트 경로를 선별하는 역량이다.

</details>

- 도구 파편화로 인한 경보 피로를 근본적으로 해결하기 위해, 배포 전 코드 스캐닝과 런타임 보호(CWPP, CSPM)를 단일 데이터 모델로 융합하고, 팩트 기반 **위험 우선순위화** 및 원본 코드 추적성(Traceability)을 보장하는 **CNAPP 팩트 거버넌스** 확립 필수이다.

#### 한줄 요약

- 멀티 클라우드 전주기 팩트 위험 관리를 위해 단일 그래프 기반 공격 경로를 식별하는 CNAPP 거버넌스를 구축한다.
