## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **역할 기반 접근 제어(Role-Based Access Control, RBAC)**: 사용자 개인에게 권한을 직접 매핑하지 않고, 직무(Role) 단위로 권한을 묶어 배정하는 간접 접근 통제 모델.

</details>

- 정의/개념: 직무 역할에 권한을 묶는 **RBAC**
- 배경/필요성: 개인별 직접 권한은 **관리 복잡성•잔존 권한** 유발

#### 한줄 요약

- 직무별 역할에 권한을 그룹화하고 사용자를 역할에 매핑하여 최소 권한 관리 효율성을 극대화함.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **역할 계층(Role Hierarchy)**: 상위 역할이 하위 역할의 모든 공통 권한을 상속받는 구조.
- **세션 활성화(Session Activation)**: 부여된 여러 역할 중 현재 세션에서 필요한 특정 역할만을 선택적 활성화하는 메커니즘.
- **정적 직무 분리(Static Separation of Duty, SSD)**: 동일 사용자가 상충되는 두 개 이상의 역할을 동시에 부여받는 것(Assignment)을 금지하는 통제.
- **동적 직무 분리(Dynamic Separation of Duty, DSD)**: 동일 사용자가 상충되는 두 개 이상의 역할을 동시에 배정받을 수는 있으나, 한 세션에서 동시에 활성화(Activation)하는 것을 제한하는 통제.

</details>

- 사용자(User)-역할(Role)-권한(Permission) 3계층 간접 맵핑으로 관리 효율성 제공.
- **역할 계층(Role Hierarchy)** 상속 관계 및 **세션 활성화(Session Activation)** 기반 최소 권한 적용.
- 부정 예방을 위한 **정적 직무 분리(SSD)** 및 **동적 직무 분리(DSD)** 제약조건 집행.

#### 한줄 요약

- 3계층 간접 매핑, 역할 계층 상속, 세션 활성화 및 SSD/DSD 직무 분리 통제를 제공함.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **사용자(User)**: 시스템에 접근하는 개별 주체(사람, 시스템 프로세스).
- **역할(Role)**: 직무 수행을 위해 정의된 권한들의 집합체.
- **권한(Permission)**: 특정 자원 객체(Object)에 대한 허용 행위(Operation/Action) 조합.
- **자원(Resource/Object)**: 접근 제어의 보호 대상이 되는 파일, 데이터베이스, API 엔드포인트.

</details>

```text
RBAC 접근 제어 구조
├─ 사용자•역할: 주체와 직무 권한 묶음
├─ 권한: 자원•허용 행위 조합
├─ 자원•행위: 권한의 대상•동작
├─ 계층•직무 분리: 상속•상충 통제
└─ 세션•감사: 역할 활성화•사용 추적
```

| 구성요소 | 책임 |
|:---|:---|
| 사용자 | 시스템 주체로서 1개 이상의 직무 **역할(Role)**에 배정됨 |
| 역할 | 직무 단위 권한 집합체로서 **사용자**와 **권한** 간 맵핑 매개 |
| 권한 | 자원(Object)과 실행 가능한 행위(Operation)의 바인딩 세트 |
| 자원 | 데이터베이스, 시스템 파일, API 등 보호 대상 객체 |
| 계층•직무 분리 | 상위 역할 권한 상속 및 **SSD/DSD** 직무 분리 규칙 집행 |

#### 한줄 요약

- 사용자, 역할, 권한, 자원 및 계층/직무 분리 통제엔진 구조로 작동함.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **세션(Session)**: 사용자가 접속하여 활성화시킨 역할 세트의 런타임 범위.
- **사용자•역할 배정 검증**: 접속 요청 사용자가 지정 역할을 정식 할당받았는지 확인하는 단계.
- **동적 직무분리 검증**: 현재 활성화하려는 역할이 기존 세션 역할과 DSD 충돌이 없는지 대조하는 단계.
- **역할 계층•권한 해석**: 계층 관계상 직계/상속 권한을 최종 집계하는 단계.
- **자원•행위 인가 판정**: 요청 대상 객체 및 연산이 활성 권한 범위 내에 있는지 판정하는 단계.
- **인가•사용 기록**: 요청 내역 및 승인/거부 판정을 audit log로 남기는 단계.

</details>

```text
역할 활성화•자원 접근 요청
            │
            ▼
1. 사용자•역할 배정 검증
            │
            ▼
2. 동적 직무분리 검증
            │
            ├─ 상충 ── 접근 거부
            │
            └─ 통과 ── 3. 역할 계층•권한 해석
                                  │
                                  ▼
                       4. 자원•행위 인가 판정
                                  │
                      ┌───────────┴───────────┐
                      │                       │
                    거부                    허용
                      │                       │
                      └─ 5. 인가•사용 기록 ───┘
```

### 동작 원리

1. **사용자•역할 배정 검증**: 사용자가 배정받은 역할 유효성 확인.
2. **동적 직무분리 검증**: 동일 세션 내 **DSD(동적 직무 분리)** 규칙 위반 여부 확인.
3. **역할 계층•권한 해석**: **역할 계층(Role Hierarchy)**에 따른 하위 공통 권한 상속 수집.
4. **자원•행위 인가 판정**: 요청한 자원 객체 및 Action에 대한 최종 인가 판정.
5. **인가•사용 기록**: 성공/실패 내역을 보안 감사 기록으로 보존.

#### 한줄 요약

- 역할 배정 검증, DSD 동적 분리 체크, 역할 계층 권한 집계, 인가 판정 및 감사 로그 저장을 수행함.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **기본 RBAC(Flat RBAC / RBAC0)**: 사용자, 역할, 권한 간 매핑만 존재하는 가장 기본적인 구조.
- **계층 RBAC(Hierarchical RBAC / RBAC1)**: 역할 간 상하 관계를 도입하여 상위 역할이 하위 역할의 권한을 상속받는 모델.
- **제약 RBAC(Constrained RBAC / RBAC2)**: 정적(SSD) 및 동적(DSD) 직무 분리 제약조건을 추가한 모델.

</details>

| RBAC 모델 | Flat RBAC (RBAC0) | Hierarchical RBAC (RBAC1) | Constrained RBAC (RBAC2) | Unified RBAC (RBAC3) |
|:---|:---|:---|:---|:---|
| 핵심 특징 | 사용자-역할-권한 기본 맵핑 | 역할 간 권한 상속 구조 | **SSD/DSD** 직무 분리 제약 | 계층(RBAC1)과 제약(RBAC2) 통합 |
| 적용 환경 | 소규모 직무 환경 | 대기업 조직 상하 관계 | 기안-결재 상충 업무 | 대규모 금융/공공 엔터프라이즈 |
| 장단점 | 단순함 / 상속 불가 | 권한 재사용 / 구조 복잡 | 부정 예방 / 제약 충돌 유의 | 통합 통제 / 높은 설계 난이도 |

#### 한줄 요약

- Flat RBAC(RBAC0), Hierarchical RBAC(RBAC1), Constrained RBAC(RBAC2) 및 Unified RBAC(RBAC3)로 발전됨.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **ANSI INCITS 359-2012**: NIST RBAC 표준 모델 및 API 규격을 정의한 정보기술 미국 국가 표준.
- **NIST SP 800-53 Rev. 5**: 연방 정보 시스템을 위한 접근 통제(AC) 모범 사례 기준 지침.
- **역할 폭발(Role Explosion)**: 세분화된 예외 권한 요구로 인해 수많은 미세 역할이 양산되어 관리가 불능 상태에 빠지는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 표준 미비에 따른 인가 구현 혼선 | **ANSI INCITS 359-2012** 스펙 적용 | 역할, 계층, SSD/DSD의 표준화된 모듈화 |
| 권한 남용 및 잔존 권한 위협 | **NIST SP 800-53 Rev. 5** 기준 정기 권한 재인증(Recertification) | 퇴사자/전보자 즉시 권한 회수 |
| 예외 직무 양산으로 **역할 폭발(Role Explosion)** | ABAC(속성 기반 접근 제어)와 혼합 적용(RBAC + ABAC) | 미세 파라미터 조건은 ABAC로 처리하여 역할 수 억제 |

#### 한줄 요약

- ANSI INCITS 359-2012 표준 준수, NIST SP 800-53 권한 재인증 및 역할 폭발 방지용 RBAC-ABAC 하이브리드 설계를 집행함.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **최소 권한 원칙(Principle of Least Privilege)**: 사용자가 업무 수행에 꼭 필요한 최소한의 역할과 세션 권한만을 부여받아야 한다는 보안 기본 준칙.

</details>

- **최소 권한 원칙**에 입각하여 조직 규모에 맞는 **RBAC 모델(RBAC0~3)**을 선택하고, 정기적인 권한 재인증과 **SoD(직무 분리)** 통제를 지속 관리.

#### 한줄 요약

- 조직 규모별 **RBAC0~3** 선택과 **SoD•재인증** 적용
