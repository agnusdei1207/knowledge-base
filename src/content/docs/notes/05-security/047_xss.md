## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **교차 사이트 스크립팅(Cross-Site Scripting, XSS)**: 검증되지 않은 비신뢰 클라이언트 입력값이 애플리케이션의 웹 응답 문서에 포함되어 희생자의 브라우저에서 악성 자바스크립트로 해석 실행되는 취약점.

</details>

- 정의/개념: 비신뢰 입력이 브라우저에서 실행되는 **XSS**
- 배경/필요성: DOM 렌더링은 **입력-실행 경계** 붕괴를 유발

#### 한줄 요약

- 비신뢰 입력을 브라우저에서 스크립트 코드로 해석하지 못하도록 문맥별 출력 인코딩 및 정화를 집행함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하이퍼텍스트 마크업 언어(HyperText Markup Language, HTML)**: 웹 페이지 구조를 정의하는 표준 마크업 포맷.
- **통합 자원 위치 지정자(Uniform Resource Locator, URL)**: 웹 상의 자원 위치 및 스키마 프로토콜을 명시하는 주소 체계.
- **문서 객체 모델(Document Object Model, DOM)**: HTML/XML 문서를 객체 트리 구조로 표현하고 스크립트 조작을 허용하는 API 인터페이스.
- **출력 문맥(Output Context)**: 데이터가 출력되는 HTML Body, Attribute, JavaScript, URL 등의 구문 해석 위치.
- **출력 인코딩(Output Encoding)**: 출력 문맥별 예약 특수문자(<, >, ", ', & 등)를 무해한 엔티티 문자로 변환 처리하는 기술.
- **DOM 실행 경로(DOM Sink / Source)**: location.hash 등 취약한 입력(Source)이 innerHTML 등 위험한 실행점(Sink)으로 전달되는 흐름.

</details>

- 서버 저장/반사 응답뿐만 아니라 클라이언트 단 **DOM 실행 경로(DOM Sink / Source)**에서도 발현.
- **HTML**, Attribute, JavaScript 및 **URL** 등 데이터가 렌더링되는 **출력 문맥**에 입각한 **출력 인코딩** 필수.
- AJAX/REST API 응답으로 유입되는 비신뢰 JSON/XML 데이터에 대해서도 동일 방어 적용.

#### 한줄 요약

- **출력 문맥별 인코딩** 없이는 스크립트 해석 차단 불가

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **HTML 정화(HTML Sanitization)**: WYSIWYG 에디터 등 사용자 HTML 입력을 수용할 때, Script/Iframe 태그 및 onerror 속성 등 위험 요소를 허용목록(Allowlist) 기반으로 안전 삭제하는 처리.
- **콘텐츠 보안 정책(Content Security Policy, CSP)**: 브라우저가 로드하여 실행할 수 있는 스크립트의 출처(Domain) 및 Inline execution 허용 여부를 제한하는 HTTP 헤더 방어 체계.

</details>

```text
XSS 방어 구조
├─ 비신뢰 유입: 입력•URL•외부 데이터 수집
├─ 출력 문맥: HTML•속성•URL•스크립트 구분
├─ 렌더링 지점: 템플릿•DOM API 반영
├─ 인코더•정화기: 문맥 인코딩•HTML 정화
└─ 브라우저 통제: CSP•쿠키로 피해 제한
```

| 구성요소 | 책임 |
|:---|:---|
| 비신뢰 유입 | 폼 입력, URL 매개변수 및 외부 API 데이터 수집 |
| 출력 문맥 | **HTML** Body, HTML Attribute, JavaScript Variable, **URL** 파라미터 구분 |
| 렌더링 지점 | 클라이언트 템플릿 엔진 및 **DOM** API 매핑 |
| 인코더•정화기 | 문맥 맞춤 **출력 인코딩** 및 허용목록 기반 **HTML 정화** |
| 브라우저 통제 | **CSP** 헤더 및 HttpOnly 쿠키 속성을 적용하여 피해 국소화 |

#### 한줄 요약

- 비신뢰 데이터 유입부터 렌더링 지점 구문 분석, 출력 인코더 적용 및 브라우저 헤더 방어로 스크립트 실행을 통제함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **innerHTML**: 문자열을 직접 HTML DOM 트리로 해석하여 주입하는 속성으로 비신뢰 데이터 매핑 시 XSS를 유발하는 대표적인 DOM Sink.
- **비신뢰 데이터 저장•반사**: 입력 데이터가 DB에 저장되거나 HTTP 응답에 인코딩 없이 그대로 노출되는 단계.
- **HTML•DOM 구문 해석**: 브라우저 엔진이 응답 문자를 파싱하여 자바스크립트로 실행하는 단계.
- **피해자 출처에서 스크립트 실행**: 애플리케이션의 Same-Origin 권한을 얻어 스크립트가 구동되는 단계.
- **세션•문서 데이터 접근**: document.cookie, LocalStorage 또는 DOM에 접근하여 민감 정보를 탈취하는 단계.

</details>

```text
악성 스크립트 포함 데이터
          │
          ▼
1. 비신뢰 데이터 저장•반사
          │
          ▼
취약한 웹 응답
          │
          ▼
2. HTML•DOM 구문 해석
          │
          ▼
3. 피해자 출처에서 스크립트 실행
          │
          ▼
4. 세션•문서 데이터 접근
          │
          ▼
탈취 데이터•위조 요청
```

### 동작 원리

1. 비신뢰 데이터 저장•반사: 검증되지 않은 악성 데이터가 DB 저장 또는 응답에 결합.
2. HTML•DOM 구문 해석: 브라우저 파서가 입력 데이터를 코드로 실행 처리.
3. 피해자 출처에서 스크립트 실행: 희생자 브라우저 세션 권한 기반 악성 script 구동.
4. 세션•문서 데이터 접근: 쿠키, 세션 토큰 탈취 및 CSRF/XHR 위조 요청 집행.

#### 한줄 요약

- 비신뢰 데이터의 인입, 브라우저 렌더링 구문 해석, 동일 출처 스크립트 실행 및 세션 접근 단계를 무력화함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **저장형 XSS(Stored XSS)**: 악성 스크립트가 DB, 게시판 등에 영구 저장된 후 사용자가 해당 페이지 열람 시 자동 실행되는 공격.
- **반사형 XSS(Reflected XSS)**: URL 파라미터 등에 포함된 악성 스크립트가 서버를 거쳐 즉시 응답 페이지로 반사되어 실행되는 공격.
- **DOM 기반 XSS(DOM-based XSS)**: 서버를 거치지 않거나 서버 응답과 관계없이 클라이언트 자바스크립트가 DOM 환경을 직접 조작하여 발생하는 공격.

</details>

| XSS 유형 | 저장형 | 반사형 | DOM 기반 |
|:---|:---|:---|:---|
| 적용 기준 | 저장값 출력 시 | 요청값 반영 시 | 클라이언트 반영 시 |
| 핵심 특징 | 저장 후 불특정 다수 지속 확산 | 피싱 링크 클릭 유도 단발 실행 | **DOM** 소스/싱크 처리 시 런타임 발생 |
| 한계 | 영향력 및 파급도 극대 | 피해자 클릭 유도 필요 | 서버 사이드 WAF 검사 차단 한계 |

#### 한줄 요약

- 발현 메커니즘에 따라 저장형(Stored), 반사형(Reflected), 클라이언트 DOM 기반(DOM-based)으로 분류함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **MITRE CWE-79**: 웹 페이지 생성 중 입력의 부적절한 무력화(Cross-site Scripting) 약점 명세.
- **OWASP ASVS 5.0.0**: 문맥별 엔티티 인코딩 및 CSP 규격을 명시한 검증 표준.
- **HttpOnly/Secure/SameSite**: 스크립트에 의한 쿠키 접근을 전면 금지하고 전송 경로를 제어하는 쿠키 보안 속성.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 문맥 미고려 인코딩 시 공격 성립 | **MITRE CWE-79** 지침 준수 문맥별 인코딩 적용 | 브라우저 파서의 스크립트 실행 차단 |
| 개발자별 정화 로직 편차 | **OWASP ASVS 5.0.0** 기준 HTML Sanitizer 도입 | 허용목록 기반 안전 태그만 통과 |
| innerHTML 및 세션 쿠키 노출 | textContent 사용, **CSP** 적용 및 **HttpOnly/Secure/SameSite** 설정 | 자바스크립트에 의한 세션 토큰 탈취 방지 |

#### 한줄 요약

- textContent 사용 및 문맥별 이스케이프를 기본 적용하고, HttpOnly 쿠키 속성과 CSP 헤더를 심층 적용함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **XSS 통제 선택 기준(XSS Control Criteria)**: 일반 출력에는 Contextual Encoding, 풍부한 텍스트에는 HTML Sanitizer, 잔여 스크립트에는 CSP 및 HttpOnly 속성을 다층 적용하는 방어 원칙.

</details>

- **XSS 통제 선택 기준**에 따라 일반 데이터는 **출력 인코딩**, HTML 텍스트는 **HTML 정화**, 잔여 위협은 **CSP** 및 HttpOnly 쿠키로 심층 방어.

#### 한줄 요약

- 일반 출력은 **인코딩**, HTML은 **정화**, 잔여 위협은 CSP
