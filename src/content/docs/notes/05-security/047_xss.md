## 미리 알고가기

- **XSS(Cross-Site Scripting, 엑스에스에스)**: CSS와의 혼동을 피하려 `X`로 Cross를 표기하며, 비신뢰 데이터가 브라우저 스크립트로 실행되는 취약점
- **DOM(Document Object Model, 돔)**: 머리글자를 한 단어처럼 읽으며, HTML 문서를 객체 구조로 표현·변경하는 인터페이스
- **출력 문맥**: 외부 데이터가 삽입되는 HTML 본문·속성·URL·스크립트 등의 해석 위치
- **출력 인코딩**: 출력 문맥별 특수문자를 코드가 아닌 데이터로 표시하는 처리
- **HTML 정화**: 사용자 HTML에서 위험 태그·속성·URL을 제거하고 허용 요소만 유지
- **CSP(Content Security Policy, 씨에스피)**: 실행 가능한 스크립트와 리소스 출처를 제한하는 브라우저 정책
- **innerHTML(이너 에이치티엠엘)**: 문자열을 HTML 구문으로 해석해 DOM에 삽입하는 API


- **흐름 기호(↓·→·X)**: 아래·다음·차단의 절차 방향과 금지를 표시
## Ⅰ. 개요

- 정의/개념: 비신뢰 데이터가 브라우저 코드로 실행됨
- 기존 한계: 비신뢰 출력을 코드와 분리하지 않으면 실행됨
- **배경/필요성**: 문맥별 인코딩과 위험 HTML 정화

### 쉽게 이해하기 (학습용)

- 비신뢰 데이터가 브라우저 코드가 되면 피해자의 세션 권한으로 실행된다.

## Ⅱ. 특징

- 저장·반사·DOM 경로에서 스크립트가 실행된다.
- HTML·속성·URL마다 안전한 인코딩이 다르다.
- 사용자 HTML은 검증된 정화기로 제한해야 한다.
- CSP·쿠키 속성은 실행 피해를 줄이는 보조 통제이다.

### 쉽게 이해하기 (학습용)

- 출력 문맥에 맞는 인코딩이 어긋나면 필터를 우회할 수 있다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 비신뢰 유입 | 입력·URL·메시지·외부 API |
| 출력 문맥 | HTML·속성·URL·스크립트 |
| 렌더링 지점 | 템플릿·DOM API가 데이터를 반영 |
| 인코더/정화기 | 텍스트 표시 및 HTML 구문 정화 |
| 브라우저 통제 | CSP·쿠키 속성으로 실행 피해 제한 |

```text
[입력·URL·외부 API] → [서버 템플릿 / DOM API] → [브라우저 출력 문맥]
                                │
                        문맥별 인코딩·HTML 정화
                                ↓
                         [텍스트 표시 / 제한 실행]
```

### 쉽게 이해하기 (학습용)

- 비신뢰 데이터가 렌더링 지점에서 코드로 해석되지 않게 경계를 지킨다.

## Ⅳ. 원리 및 절차 흐름도

```text
경로식별
   ↓
문맥분류
   ↓
안전렌더
   ↓
콘텐츠정화
   ↓
회귀검증
```

| 절차 | 설명 |
|:---|:---|
| 경로식별 | 사용자 데이터의 유입 경로 식별함 |
| 문맥분류 | HTML·속성 등 출력 위치 구분함 |
| 안전렌더 | 이스케이프와 텍스트 API 사용함 |
| 콘텐츠정화 | 허용된 HTML의 악성 구문을 정화함 |
| 회귀검증 | CSP 적용 및 우회 공격 검증함 |

> 요약: 경로 식별 후 문맥별 안전 렌더링 및 정화함

### 쉽게 이해하기 (학습용)

- 데이터 경로와 출력 문맥을 찾고 안전한 렌더링과 정화를 적용한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | 저장형 | 반사형 | DOM 기반 |
|:---|:---|:---|:---|
| 적용 기준 | 저장값이 출력될 때 | 요청값이 반영될 때 | 클라이언트 반영 시 |
| 핵심 특징 | 저장 후 여러 사용자에게 반복 실행 | 요청값이 응답에 반영돼 실행 | 클라이언트에서 DOM 변경 후 실행 |
| 한계 | 다수 사용자·관리자에게 지속 확산 | 조작 링크로 피해자 유도 필요 | 서버 응답 검사로 탐지 곤란 |

> 요약: 데이터 경로와 반영 방식에 따라 3종 구분함

### 쉽게 이해하기 (학습용)

- 저장 위치와 반영 주체에 따라 저장형·반사형·DOM 기반으로 나뉜다.

## Ⅵ. 실무 사례

1. 게시글 출력에 **HTML 문맥 이스케이프 적용**

### 쉽게 이해하기 (학습용)

- 사용자가 작성한 게시글은 HTML로 직접 삽입하지 않고 문맥에 맞게 이스케이프해 스크립트가 다른 이용자의 브라우저에서 실행되지 않게 한다.

## Ⅶ. 결론

- 비신뢰 입력이 브라우저 코드로 실행되는 위험을 제거하기 위해 출력 문맥·허용 HTML·DOM 사용 방식·CSP 보조 효과를 검토하여, 문맥별 인코딩과 정화를 적용해야 한다.

### 쉽게 이해하기 (학습용)

- XSS는 출력 문맥별 인코딩과 HTML 정화를 함께 적용해야 한다.
