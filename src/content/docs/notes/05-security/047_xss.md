## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **XSS(Cross-Site Scripting)** 는 비신뢰 데이터가 피해자의 브라우저에서 스크립트로 실행되는 취약점이다.

</details>

- 정의/개념: **XSS** 는 비신뢰 데이터가 웹 문서의 실행 가능한 스크립트 문맥에 삽입되어 피해자 브라우저에서 공격자 코드를 실행하게 하는 웹 취약점
- 배경/필요성: 문자열 필터만으로는 문맥별 해석 차이에 따른 **스크립트 실행 차단 불가**

#### 한줄 요약

- 비신뢰 데이터가 브라우저 코드가 되면 피해자의 세션 권한으로 실행된다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **HTML(HyperText Markup Language)** 은 웹 문서의 구조와 내용을 표현하는 마크업 언어다.
- **URL(Uniform Resource Locator)** 은 웹 자원의 위치와 접근 방법을 나타내는 식별자다.
- **DOM(Document Object Model)** 은 HTML 문서를 객체 구조로 표현하고 스크립트로 변경하는 인터페이스다.
- **API(Application Programming Interface)** 는 소프트웨어 구성요소 간 기능 호출 규약이다.
- **출력 문맥** 은 외부 데이터가 삽입되는 HTML 본문•속성•URL•스크립트 등의 해석 위치다.
- **출력 인코딩** 은 문맥별 특수문자를 코드가 아닌 데이터로 표시한다.
- **DOM 실행 경로** 는 클라이언트 스크립트가 비신뢰 데이터를 위험한 DOM API에 넣어 브라우저에서 코드로 해석되게 하는 경로다.

</details>

- 저장•반사•DOM의 **다중 실행 경로**
- HTML•속성•URL별 **문맥 인코딩**
- 정화•CSP•쿠키의 **다층 방어**

#### 한줄 요약

- 출력 문맥에 맞는 인코딩이 어긋나면 필터를 우회할 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **HTML 정화** 는 사용자 HTML에서 위험 태그•속성•URL을 제거하고 허용 요소만 유지한다.
- **CSP(Content Security Policy)** 는 실행 가능한 스크립트와 리소스 출처를 제한하는 브라우저 정책이다.

</details>

```mermaid
block-beta
  columns 3
  A["비신뢰 유입"]
  B["출력 문맥"]
  C["렌더링 지점"]
  D["인코더•정화기"]
  E["브라우저 통제"]
  A --- B
  B --- D
  D --- C
  C --- E
```

| 구성요소 | 책임 |
|:---|:---|
| 비신뢰 유입 | 입력•URL•메시지•외부 API의 **데이터 수집** |
| 출력 문맥 | **HTML•속성•URL•스크립트** 구분 |
| 렌더링 지점 | 템플릿•DOM API에 **데이터 반영** |
| 인코더•정화기 | **문맥 인코딩•HTML 정화** 수행 |
| 브라우저 통제 | CSP•쿠키 속성으로 **피해 제한** |

#### 한줄 요약

- 비신뢰 데이터가 렌더링 지점에서 코드로 해석되지 않게 경계를 지킨다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **innerHTML** 은 문자열을 HTML 구문으로 해석해 DOM에 삽입하므로 비신뢰 데이터에 사용하면 위험하다.

</details>

```mermaid
sequenceDiagram
    participant 공격자
    participant 응용
    participant 브라우저 as 피해자 브라우저
    participant 공격서버 as 공격자 서버
    공격자->>응용: 악성 스크립트 포함 데이터
    응용->>응용: 1. 비신뢰 데이터 저장•반사
    응용-->>브라우저: 취약한 웹 응답
    브라우저->>브라우저: 2. HTML•DOM 구문 해석
    브라우저->>브라우저: 3. 피해자 출처에서 스크립트 실행
    브라우저->>브라우저: 4. 세션•문서 데이터 접근
    브라우저-->>공격서버: 탈취 데이터•위조 요청
```

**동작 원리**

1. **비신뢰 데이터 저장•반사**: 입력이 출력 문맥의 구문으로 응답에 포함
2. **HTML•DOM 구문 해석**: 브라우저가 입력을 데이터가 아닌 코드로 판독
3. **피해자 출처에서 스크립트 실행**: 응용과 동일한 출처 권한 획득
4. **세션•문서 데이터 접근**: 사용자 권한으로 정보 탈취•동작 수행

#### 한줄 요약

- 데이터 경로와 출력 문맥을 찾고 안전한 렌더링과 정화를 적용한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **저장형 XSS** 는 서버에 저장된 공격 문자열이 여러 사용자의 브라우저에서 실행되는 유형이다.
- **반사형 XSS** 는 요청값에 포함된 공격 문자열이 응답에 반영되어 실행되는 유형이다.
- **DOM 기반 XSS** 는 클라이언트 DOM 변경 경로에서 공격 문자열이 실행되는 유형이다.

</details>

| XSS 유형 | 저장형 | 반사형 | DOM 기반 |
|:---|:---|:---|:---|
| 적용 기준 | **저장값 출력** 시 | **요청값 반영** 시 | **클라이언트 반영** 시 |
| 핵심 특징 | **저장 후 반복 실행** | **요청값 반영 실행** | DOM 변경 후 실행 |
| 한계 | 다수 사용자에게 **지속 확산** | 조작 링크로 **피해자 유도** 필요 | 서버 응답 검사로 **탐지 곤란** |

#### 한줄 요약

- 저장 위치와 반영 주체에 따라 저장형•반사형•DOM 기반으로 나뉜다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **CWE(Common Weakness Enumeration)-79** 는 웹 페이지 생성 중 입력의 부적절한 중화를 정의한다.
- **OWASP(Open Worldwide Application Security Project)** 는 애플리케이션 보안 지침을 공개하는 비영리 프로젝트다.
- **ASVS(Application Security Verification Standard) 5.0.0** 은 출력 인코딩•정화•브라우저 보안 요구를 제시한다.
- **HttpOnly** 는 스크립트의 세션 쿠키 접근을 제한하는 속성이다.
- **Secure** 는 암호화 연결에서만 쿠키를 전송하게 하는 속성이다.
- **SameSite** 는 교차 사이트 요청의 쿠키 전송 범위를 제한하는 속성이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 출력 문맥을 구분하지 않으면 인코딩이 공격 구문을 보존 | **MITRE CWE-79** 기준으로 문맥별 처리 | 브라우저의 **코드 실행** 차단 |
| 인코딩•정화 요구가 없으면 구현별 방어 편차 | **OWASP ASVS 5.0.0** 적용 | 개발•검증의 **요구 일관성** 확보 |
| innerHTML 사용과 세션 접근으로 피해 확대 | **innerHTML 제거•CSP** 와 쿠키 속성 적용 | 실행 경로와 **세션 피해** 제한 |

#### 한줄 요약

- 사용자가 작성한 게시글은 HTML로 직접 삽입하지 않고 문맥에 맞게 이스케이프해 스크립트가 다른 이용자의 브라우저에서 실행되지 않게 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

</details>

- 일반 출력은 **문맥별 인코딩**, 사용자 HTML은 **허용목록 정화**, 잔여 위험은 **CSP** 적용

#### 한줄 요약

- XSS는 출력 문맥별 인코딩과 HTML 정화를 함께 적용해야 한다.
