## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시큐어 코딩(Secure Coding)**: 소프트웨어 개발 생애주기(SDLC)의 구현(Implementation) 단계에서, 프로그래밍 언어 및 프레임워크의 보안 취약점(SQL 인젝션, XSS, 메모리 버퍼 오버플로우, 비인가 권한 상승 등)을 유발할 수 있는 잠재적 보안 약점(CWE)을 사전에 정의된 표준 가이드라인에 따라 코딩 시점에 선제적으로 제거하는 개발 프랙티스.
- **Shift-Left 보안 패러다임**: 배포 후 운영(Ops) 단계에서 침투 테스트나 WAF로 결함을 땜질하는 사후 대응 방식에서 탈피하여, 기획·설계·구현 등 개발 생애주기 초기 단계로 보안 검증을 전진 배치함으로써 취약점 조치 비용을 90% 이상 절감하는 개발 방법론.

</details>

- 정의/개념: NIST SSDF(SP 800-218) 및 KISA 소프트웨어 개발보안 가이드에 기반하여 **표준 코딩 규칙 제정 $\rightarrow$ 안전한 기본값(Secure Defaults) 템플릿 배포 $\rightarrow$ 피어 코드 리뷰(Peer Review) $\rightarrow$ CI/CD SAST/DAST 자동 검증 및 배포 차단(Quality Gate)** 을 집행하는 **소프트웨어 보안 내재화 아키텍처**
- 배경/필요성: 운영 환경 배포 후 발견된 보안 취약점의 수정 비용은 개발 단계 대비 최대 30~100배에 달하며, 수동 진단만으로는 개발자의 휴먼 에러를 통제할 수 없으므로 자동화된 엔지니어링 파이프라인 구축 요구

#### 한줄 요약
- 표준 가이드 수립과 안전 기본값 템플릿, 피어 리뷰 및 SAST/DAST CI/CD 게이트를 통해 결함을 선제 제거한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **안전한 기본값(Secure by Default / Secure Defaults)**: 개발자가 보안 설정을 별도로 명시하지 않더라도 프레임워크 자체가 가장 안전한 방식(예: 자동 파라미터 바인딩, 자동 HTML 이스케이프, 세션 쿠키 `HttpOnly/SameSite` 기본 적용)으로 동작하도록 설계된 아키텍처 원칙.
- **품질 게이트(Quality Gate / Deployment Gate)**: CI/CD 파이프라인 빌드 시 SAST 정적 분석 결과가 사전에 정의된 보안 기준(예: Critical/High 취약점 0건)을 충족하지 못하면 운영 배포를 즉각 중단시키는 자동화 차단 장치.

</details>

- **7대 보안 약점(KISA) 기준 표준화**: 입력 데이터 검증 및 표현, 보안 기능, 시간 및 상태, 에러 처리, 코드 오류, 캡슐화, API 오용
- **정적 분석(SAST)과 피어 리뷰의 상호보완**: SAST는 기계적 문법 결함(SQLi, Buffer Overflow)을 전수 스캔하고, 피어 리뷰는 비즈니스 로직 결함(금액 변조, BOLA)을 정밀 검증
- **추적 가능한 거버넌스(NIST SSDF 연동)**: 보안 예외 신청에 대한 승인 절차 및 기한부 만료(TTL) 정책을 통한 기술 부채 통제

#### 한줄 요약
- 7대 보안 약점 표준화, Secure by Default 프레임워크, SAST/피어리뷰 결합, CI/CD Quality Gate를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정적 분석(SAST) vs 동적 분석(DAST)**:
  - **SAST (Static Application Security Testing)**: 소스코드와 바이너리를 실행하지 않고 정적 구문 트리(AST)를 분석하여 코딩 결함 탐지.
  - **DAST (Dynamic Application Security Testing)**: 실행 중인 웹 애플리케이션에 실제 악성 HTTP 요청을 전송하여 런타임 취약점 식별.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 표준 가이드라인 및 아키텍처 계층 (Rule Definition & SSDF) ]       │
│  ├─ KISA 7대 보안 약점 가이드 & OWASP Top 10 시큐어 코딩 표준 제정      │
│  └─ [ 2. 안전한 기본값 프레임워크 배포 (Secure Defaults & Safe APIs) ]   │
│       └─ Spring Security 기본 템플릿, ORM 매핑, Secure Logger 라이브러리│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (개발자 소스코드 구현)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 1차 인적 검증 계층: 피어 코드 리뷰 (Peer Code Review) ]            │
│  └─ [ 자동화 툴이 식별 불가능한 비즈니스 로직 및 권한 인가(BOLA) 검증 ]  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (Git Pull Request / Merge)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 2차 기계 검증 계층: CI/CD 자동화 Quality Gate (SAST / SCA) ]       │
│  ├─ SAST (SonarQube/Fortify): 문법 결함, 하드코딩된 시크릿 정적 스캔    │
│  ├─ SCA (Snyk/Trivy): 오픈소스 취약 라이브러리(CVE) 및 라이선스 점검    │
│  └─ [ 배포 판정: Critical/High 0건 미충족 시 빌드 파이프라인 즉각 차단 ]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (검증 통과 시 프로덕션 배포)
                                     ▼
[ 프로덕션 릴리즈 ➔ DAST 런타임 스캔 및 침해 모니터링 피드백 ]
```

선의 의미: 표준 가이드와 프레임워크를 기반으로 코딩 후, 피어 리뷰와 CI/CD SAST/SCA Quality Gate를 거쳐 안전한 소프트웨어를 배포하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **시큐어 코딩 표준 가이드** | 언어별(Java, C++, Python, JS) 금지 함수 및 안전 코딩 표준 규칙 명문화 | NIST SSDF / KISA |
| **안전 기본값 프레임워크** | 개발자가 별도 설정 없이도 인젝션/XSS가 원천 방어되도록 구현된 내부 공통 라이브러리 | Secure Defaults |
| **피어 코드 리뷰** | 비즈니스 로직 결함, 권한 우회, 트랜잭션 무결성 결함을 인적 교차 검토 | Logic Verification|
| **SAST 정적 분석기** | 소스코드 전수 검사를 통해 하드코딩된 암호키, 미검증 입력값, 취약 함수 자동 적발 | Static Scan |
| **SCA 오픈소스 분석기** | 서드파티 의존성 라이브러리의 알려진 취약점(CVE) 및 공급망 위험 검사 | Dependency Scan |
| **CI/CD Quality Gate** | 정의된 보안 임계치 미달 시 빌드/배포를 자동 차단하여 취약 코드 배포 원천 봉쇄 | Deployment Gate |

#### 한줄 요약
- 표준 가이드, 안전 기본값 라이브러리, 피어 리뷰, SAST/SCA 스캐너, CI/CD Quality Gate가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **행정안전부/KISA 소프트웨어 개발보안 7대 항목**:
  1. 입력 데이터 검증 및 표현 (SQLi, XSS) 2. 보안 기능 (인증, 암호화) 3. 시간 및 상태 (경쟁 조건) 4. 에러 처리 5. 코드 오류 (널 포인터 역참조) 6. 캡슐화 7. API 오용.

</details>

```text
1. [표준 규칙 제정] 조직의 비즈니스 도메인 및 언어에 맞춘 시큐어 코딩 표준 가이드 및 IDE 린터(Linter) 배포
            │
            ▼
2. [시큐어 구현] 개발자가 안전 템플릿(PreparedStatement, DOMPurify)을 적용하여 기능 개발
            │
            ▼
3. [피어 리뷰 승인] Git PR 생성 ➔ 동료 개발자가 인가(RBAC) 로직 및 결제 금액 조작 가능성 검증 후 승인
            │
            ▼
4. [CI/CD 자동 검사] 파이프라인이 구동되어 SAST(정적 분석) 및 SCA(오픈소스 취약점) 자동 스캔 집행
            │
            ├─ [Critical 취약점 검출 시] ➔ 빌드 즉각 실패(Fail) 및 개발자에게 라인별 수정 권고 자동 피드백
            ▼
5. [Quality Gate 통과 및 배포] 전 항목 검증 통과 ➔ 스테이징 및 프로덕션 환경 무결성 배포 완료
```

**동작 원리**

1. **사전 결함 유입 차단**: IDE 플러그인(SonarLint)을 통해 코딩 타이핑 시점에 1차 피드백
2. **논리적 결함 인적 필터링**: 기계가 이해할 수 없는 비즈니스 규칙과 권한 모델 검증
3. **규칙 기반 전수 스캔**: 수백만 라인의 코드베이스를 추상 구문 트리(AST)로 파싱하여 취약 패턴 탐색
4. **엄격한 배포 통제**: 보안 임계값을 넘지 못한 바이너리의 운영망 유입을 파이프라인에서 하드블록
5. **폐쇄 루프 지속 개선**: 운영 중 식별된 신규 위협을 SAST 커스텀 룰셋으로 지속 환류

#### 한줄 요약
- 표준 린터 배포, 시큐어 코딩 구현, 피어 리뷰 승인, CI/CD SAST/SCA 자동 스캔, Quality Gate 배포 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시큐어 코딩 3대 품질 통제 수단 비교**: 피어 코드 리뷰(Human), 자동화 정적/동적 스캔(Tool), 안전 프레임워크(Architecture)의 비교.

</details>

| 비교 항목 | 피어 코드 리뷰 (Human Review) | 자동 정적/동적 스캔 (SAST / DAST) | 안전 프레임워크 기본값 (Architecture) |
|:---|:---|:---|:---|
| **핵심 검증 대상** | **비즈니스 로직 오류, 권한 인가 결함** | **문법적 결함(CWE), 취약 함수, 시크릿 노출** | **인젝션, XSS, 세션 설정 결함 원천 소거** |
| **장점 및 특징** | **복잡한 업무 흐름 및 도메인 결함 검증 탁월**| **대규모 소스코드를 초고속 일관되게 전수 검사**| **개발자의 코딩 실수 개입 자체를 구조적 차단** |
| **주요 한계점** | 리뷰어 역량 편차 및 시간/인력 리소스 소모 | 문맥 파악 불가로 인한 오탐(False Positive) | 레거시 시스템 및 특수 커스텀 구현 시 제약 |
| **자동화 수준** | **수동 (사람의 정밀 검토 의존)** | **완전 자동화 (CI/CD 파이프라인 연동)** | **완전 자동화 (프레임워크 런타임 강제)** |
| **SDLC 최적 단계** | **코드 구현 직후 (Pull Request 단계)** | **빌드 및 테스트 단계 (Continuous Testing)** | **아키텍처 설계 및 프레임워크 선정 단계** |

#### 한줄 요약
- 피어 리뷰는 비즈니스 로직 검증, SAST/DAST는 기계적 전수 스캔, 안전 프레임워크는 구조적 결함 소거이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-218 (Secure Software Development Framework, SSDF)**: 안전한 소프트웨어 개발을 위해 조직 준비, 소프트웨어 보호, 취약점 없는 소프트웨어 제작, 취약점 대응의 4대 핵심 영역을 규정한 미국 연방 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SAST 정적 분석기의 수천 건의 거짓 양성(False Positive) 오탐으로 인한 **개발 지연 및 개발자 반발** | **조직 룰셋 테일러링(Tailoring)을 통한 노이즈 제거 및 안전 기본값 프레임워크(Spring Security 등) 배포** | 오탐률 80% 이상 절감 및 핵심 취약점에 대한 개발팀 조치 수용성 100% 확보 |
| SAST 스캐너만 맹신하다가 **결제 금액 변조 및 BOLA 비즈니스 로직 우회 취약점이 운영망에 배포** | **배포 전 피어 코드 리뷰(Peer Review) 의무화 및 비즈니스 로직 특화 단위/통합 테스트 코드 구현** | 자동화 툴의 사각지대인 논리적 인가 결함 및 비즈니스 로직 조작 100% 선제 차단 |
| 릴리즈 일정 압박으로 임시 승인된 보안 예외 코드가 **수년간 방치되어 실제 침해 경로로 악용되는 사고** | **보안 예외 건에 대해 30~90일 기한부 만료(TTL) 관리 및 만료 시 재검증 강제 시스템** 연동 | 잊혀진 보안 취약점(기술 부채)의 영구 누적을 차단하고 지속적 코드 무결성 유지 |

#### 한줄 요약
- 룰셋 테일러링으로 오탐을 줄이고, 피어 리뷰로 로직을 검증하며, 기한부 TTL로 예외를 관리한다.

## Ⅶ. 결론

- 소프트웨어의 구조적 취약성을 설계 및 구현 단계에서 근원 차단하는 **시큐어 코딩 아키텍처**는 DevSecOps 및 공급망 보안의 가장 핵심적인 기초 인프라이며, 실무 구현 시 **NIST SSDF 기반 표준 가이드 제정**, **Secure by Default 안전 프레임워크 내재화**, **피어 코드 리뷰와 SAST/SCA의 하이브리드 검증**, **CI/CD Quality Gate를 통한 배포 자동 통제**를 결합하여 무결점 소프트웨어 개발 생태계를 완성

#### 한줄 요약
- 표준 가이드와 안전 프레임워크 및 SAST/피어리뷰 결합을 통해 결함 없는 시큐어 소프트웨어를 완성한다.
