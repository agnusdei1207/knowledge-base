## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시큐어 코딩 (Secure Coding)**: 개발자가 코딩할 때부터 해킹에 뚫리지 않도록(예: SQL 인젝션, XSS 예방), 처음부터 안전한 룰을 지키면서 프로그램을 짜는 보안 개발 체계다.

</details>

- 정의: 소프트웨어 개발 생명주기(SDLC)의 소스 구현 단계에서, 잠재적인 보안 취약점(입력 검증, 권한 관리 등) 발생을 사전에 원천 예방하는 보안 표준 및 검증 체계다.
- 배경: 개발자 개인의 코딩 역량과 양심에만 의존하면 취약점이 계속 반복해서 터지고, 나중에 운영 중에 고치려면 천문학적인 비용과 장애가 유발되기 때문이다.

#### 한줄 요약

- 소 잃고 외양간 고치지 말고, 코드 짤 때부터 가이드 지키고 스캐너 돌려서 취약점을 없애버리는 활동이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **SAST (정적 분석)**: 코드를 실행하지 않고 텍스트 파일(소스)만 쭉 훑어보면서 "어? 비밀번호 하드코딩했네?" 하고 잡아내는 스캐너다.
- **DAST (동적 분석)**: 서버를 켜놓고 해커처럼 실제로 모의 공격 패킷을 쏴보면서, 런타임에 터지는 구멍을 잡아내는 스캐너다.
- **배포 게이트 (Deployment Gate)**: 개발자가 짠 코드가 SAST나 DAST 점수를 통과 못 하면, 아예 운영 서버로 넘어가지 못하게 막아버리는 CI/CD 톨게이트 차단막이다.

</details>

- **표준 가이드 규격화**: 개발 언어와 프레임워크(Java, Python 등)에 맞춰, 뻔히 터지는 취약점(OWASP 기준)을 막기 위한 표준 시큐어 코딩 룰을 전사에 배포한다.
- **안전 API 템플릿 강제**: 개발자가 맘대로 짜다 실수하지 않게, 이미 보안 검증이 끝난 안전한 API와 라이브러리(기본값)만 쓰도록 강제한다.
- **자동화 스캔 및 배포 차단**: 사람이 눈으로 보는 걸 넘어, SAST/DAST 스캐너를 24시간 돌리고 기준 미달 시 배포 게이트(파이프라인)에서 셧다운시킨다.

#### 한줄 요약

- 룰(가이드) 정해주고, 안전한 블록(API) 주고, 다 짠 코드는 스캐너 돌려서 통과 못 하면 배포 원천 차단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **위협 모델링 (Threat Modeling)**: 개발 시작 전에 "이 기능은 회원정보 빼가기 딱 좋네, 암호화 빡세게 해" 하고 공격 시나리오를 미리 그려보는 설계 분석 기법이다.
- **동료 코드 리뷰 (Peer Code Review)**: 자동 스캐너(SAST)가 "결제 금액을 마이너스로 조작"하는 논리적 버그는 못 잡으니까, 선배나 동료가 눈으로 비즈니스 로직을 철저한 검증하는 거다.

</details>

```text
[ 시큐어 코딩 통제 아키텍처 ]

[ 1. 가이드 및 위협 모델링 ] ── ("우리 회사는 자바(Java) 쓰니까, 자바 시큐어 코딩 룰 세팅함!")
      │
      ▼
[ 2. 안전 구현 (개발 적용) ] ── ("개발팀이 룰에 맞춰서, 안전한 API 템플릿 가져다 코딩함!")
      │
      ▼
[ 3. 동료 코드 리뷰 (Peer) ] ── ("자동 툴이 못 잡는 비즈니스 권한/로직 구멍은 사람(동료)이 눈으로 체크함!")
      │
      ▼
[ 4. 자동 검증 (SAST/DAST) ] ── ("소스코드 정적 스캔하고, 모의 해킹(동적) 돌려서 취약점 털어봄!")
      │
      ▼
[ 5. 배포 게이트 및 환류 ] ── ("보안 검사 통과 못 하면 배포 셧다운! 통과한 것만 운영망 배포!")
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **가이드 및 위협 모델링** | 최신 해킹 트렌드(OWASP)를 반영한 **전사 시큐어 코딩 룰을 세팅함** | Rule |
| **안전 구현 (개발 적용)** | 개발자가 고민 안 하게 **안전하게 짜인 라이브러리(안전 기본값)를 쥐여줌** | Develop |
| **동료 코드 리뷰** | 자동화 툴이 못 잡는 **로직 우회나 권한 붕괴를 사람 눈으로 철저한 검증함** | Review |
| **자동 검증 (SAST/DAST)** | 코드를 텍스트로 분석(SAST)하고 런타임에 찔러보며(DAST) **취약점을 스캔함** | Scan |
| **배포 게이트 및 통제** | 보안 점수 미달 시 **운영망으로의 빌드/배포를 원천 원천 차단함** | Gate |

#### 한줄 요약

- 룰 세팅 $\to$ 개발 $\to$ 사람 눈(리뷰)으로 로직 체크 $\to$ 기계(스캐너)로 문법 체크 $\to$ 불합격 시 컷!

## Ⅳ. 흐름도

```text
└──────────────┬───────────────┘
               ▼

│ 3. [동료 코드 리뷰 (비즈니스 로직 철저한 검증)]

└──────────────┬───────────────┘

│ 4. [SAST/DAST 배포 게이트 판정]

└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [예외 통제 및 운영 피드백 환류]
│ ("당장 낼 오픈이라 어쩔 수 없으면 기한 정해서 예외 처리하고, 나중에 무조건 재심사!")
└──────────────────────────────┘
```

### 동작 원리

1. 규칙화: CWE, OWASP 기준을 반영하여 언어별 시큐어 코딩 가이드(룰)를 확정함.
2. 코딩: 개발자가 검증된 안전 API(Secure API) 및 안전 기본값을 사용하여 취약점 유입을 차단함.
3. 코드 리뷰: 자동화 도구가 탐지 못하는 비즈니스 로직 및 인가 결함을 동료 리뷰로 적발함.
4. 배포 판정: CI/CD 파이프라인 상에서 SAST/DAST 정적/동적 검사를 집행하고, 통과 시에만 배포함.
5. 운영 피드백/예외: 운영 중 터진 신규 취약점을 가이드에 환류하고, 미해결 예외는 시한을 두고 추적함.

#### 한줄 요약

- 룰대로 코딩하고, 사람 눈으로 비즈니스 로직 잡고, 스캐너로 오타(취약점) 잡아서 통과된 것만 배포해라.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 시큐어 코딩 통제 수단 | **동료 코드 리뷰 (Human)** | **자동 스캔 (SAST / DAST)** | **안전 프레임워크 (기본값)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | **눈썰미 좋은 선배가 후배 소스코드 째려보기** | **AI 기계가 소스코드 파일 통째로 스캐닝하기** | **처음부터 날 안 선 뭉툭하고 안전한 칼 쥐여주기** |
| 핵심 탐지 방식 | 기계가 알 수 없는 **비즈니스 로직 결함과 권한 우회를 사람이 잡아냄** | 패턴 매칭 기법으로 **명백한 코딩 실수(인젝션 등)를 수 초 만에 스캔함** | 개발자가 의도하지 않아도 **자동으로 인코딩/바인딩 되도록 강제함** |
| 장점 및 특징 | 권한 설정이나 결제 금액 조작 같은 **복잡한 논리 오류를 가장 잘 방어함** | 수십만 줄의 방대한 코드를 **지치지 않고 일관된 룰셋으로 자동 검증함** | 개발자의 실수(Human Error)가 개입할 **취약점 발생 경로 자체를 지워버림** |
| 한계 및 문제점 | 리뷰어(선배) 실력이 허접하면 **수박 겉핥기로 대충 통과시키는 리스크 발생** | 프로그램 문맥을 몰라서 안전한 코드도 취약하다고 **오탐(가짜 알람)을 난사함** | 프레임워크가 지원하지 않는 레거시 환경이나 **커스텀 특수 기능에선 못 씀** |

#### 한줄 요약

- 사람 눈(리뷰)으로 로직 잡고, 기계(스캐너)로 단순 실수 잡고, 프레임워크로 애초에 실수를 원천 원천 차단해라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SSDF**: 미국 정부가 찍어준 "안전한 소프트웨어 만들 거면 제발 이 가이드대로 프로세스 밟아라" 하는 글로벌 개발 지침이다.
- **예외 만료 (Exception Expiration)**: 오픈일 다가와서 급하게 승인 내준 취약점 코드를 1년 뒤에도 방치하지 않게, '3개월 시한부'를 걸고 날짜 지나면 쫓아가서 고치게 만드는 시스템이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 취약점 스캐너(SAST) 빡세게 돌렸는데 **결제 금액이 마이너스로 승인됨** | 스캐너는 문법적 오류(SQLi 등)만 찾을 뿐, 비즈니스 로직(금액/권한 조작)은 못 잡음 | SAST에 의존하지 않고, 동료나 선임자가 비즈니스 로직을 검증하는 **코드 리뷰 강제** | 스캐너의 한계를 극복하고, 복잡한 비즈니스 권한/로직 결함 원천 방어 |
| 코드 스캔 돌렸더니 가짜 알람이 천 개 떠서 **개발팀이 빡쳐서 스캐너 꺼버림** | 도구 세팅(룰셋 튜닝) 없이 무지성으로 돌려서 가짜 오탐 알람(False Positive)이 쏟아짐 | 도구 튜닝으로 오탐을 제거하고, 핵심 **안전 프레임워크(기본값)** 배포로 원천 에러 억제 | 보안 스캐닝의 실무 수용성을 높이고, 개발 지연(Dev Delay) 불만 최소화 |
| 급하다고 임시로 보안 예외 승인 내줬더니 **1년 뒤에 그 구멍으로 털림** | "나중에 고칠게요"라는 개발팀 말만 믿고, 보안 예외 건에 대한 추적 관리를 방치함 | 보안 예외 신청 시 기한을 부여하고, 만료 시 재검증을 강제하는 **예외 만료 시스템 연동** | 잊혀진 예외 코드(기술 부채) 방치로 인한 치명적 침해 위협 원천 제거 |

#### 한줄 요약

- 스캐너 가짜 알람(오탐) 줄여주고, 스캐너가 못 잡는 로직은 코드 리뷰로 잡고, 예외 처리한 건 날짜 지나면 조져라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **시큐어 코딩 운영 기조 (Secure Coding Baseline)**: 완벽한 툴은 없으니 도구(SAST/DAST), 사람(리뷰), 프로세스(배포 게이트/예외 관리)를 톱니바퀴처럼 맞물려 돌리는 실무 사상.

</details>

- 완벽한 코드는 없으므로, **안전 프레임워크** 배포로 초기 코딩 실수를 줄이고, 비즈니스 로직 오류는 **동료 코드 리뷰**로, 패턴 취약점은 **SAST/DAST** 자동 검사 및 **배포 게이트**로 차단하며, 어쩔 수 없는 결함은 철저한 **예외 만료 관리**로 통제하는 다층 철저한 방어 기조를 확립함

#### 한줄 요약

- 기계적 취약점은 **스캐너**, 논리 취약점은 **코드 리뷰**, 어쩔 수 없는 예외는 **시한부 통제**로 관리해라.
