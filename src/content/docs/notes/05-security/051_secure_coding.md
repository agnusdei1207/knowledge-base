## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Secure Coding (시큐어 코딩)**: SDLC 구현 단계에서 잠재적 보안 약점(CWE)을 코딩 시점에 선제 제거하는 개발 프랙티스.
- **Shift-Left Security**: 보안 검증을 운영 후반에서 기획·설계·구현 초기 단계로 전진 배치하여 조치 비용을 절감하는 전략.

</details>

- 정의/개념: SDLC 구현 단계에서 잠재적 보안 약점을 **표준 가이드라인과 안전 기본값 프레임워크에 따라 선제 제거하는 보안 기술**
- 배경/필요성: 운영 단계 사후 패치/WAF 의존 시 발생하는 **천문학적 조치 비용(설계 대비 최대 100배), 비즈니스 로직 결함 및 침해 방치**

#### 한줄 요약
- 구현 단계에서 표준 가이드와 프레임워크를 통해 소프트웨어 보안 약점을 선제적으로 원천 제거한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Secure Defaults (안전 기본값)**: 개발자가 별도 코딩을 하지 않아도 프레임워크 차원에서 XSS나 인젝션이 자동 방어되도록 구성된 환경.
- **Quality Gate**: CI/CD 파이프라인에서 보안 스캔 결과가 기준(Critical 0건 등)을 충족하지 못하면 빌드를 차단하는 게이트.

</details>

- **결함 수정 비용의 극적인 절감(Shift-Left)**: 운영 단계 패치 대비 **코딩 시점 결함 조치로 비용 및 일정 지연을 90% 이상 감축**
- **안전 기본값(Secure by Default) 아키텍처**: 개발자 개인의 실수에 의존하지 않고 **프레임워크 수준에서 인젝션, XSS, CSRF 자동 방어**
- **CI/CD 파이프라인 자동화 Quality Gate**: SAST 및 SCA 스캔 결과 **치명적 취약점 미해결 시 운영망 배포 파이프라인 즉각 차단**

#### 한줄 요약
- Shift-Left 비용 절감, Secure by Default 아키텍처, CI/CD Quality Gate 자동 배포 차단을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SAST vs SCA**: 소스코드 자체의 보안 약점을 정적 검사하는 SAST와 서드파티 오픈소스 라이브러리의 취약점을 검사하는 SCA.

</details>

```text
[시큐어 코딩 생애주기 및 파이프라인 아키텍처]
|-- 1. Governance & Standard (NIST SSDF, KISA 7대 보안 약점 표준 가이드)
`-- 2. Implementation Layer (안전 기본값 프레임워크 + IDE SonarLint 실시간 피드백)
`-- 3. Peer Review (Git PR 인가 로직, 비즈니스 규칙 교차 검증)
`-- 4. Automated CI/CD Quality Gate
    |-- SAST Engine (SonarQube/Fortify: 문법 결함, 시크릿 노출 검사)
    |-- SCA Engine (Snyk/Trivy: 오픈소스 CVE 취약점 점검)
    `-- Deployment Gate (Critical 0건 미충족 시 빌드 파이프라인 차단)
```

선의 의미: 표준 가이드와 프레임워크를 기반으로 코딩 후 피어 리뷰와 CI/CD SAST/SCA Quality Gate를 거쳐 안전한 소프트웨어를 배포하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **시큐어 코딩 가이드** | 언어별 금지 함수 및 **안전 코딩 표준 규칙 명문화** | NIST / KISA |
| **안전 기본값 프레임워크**| 별도 설정 없이도 **인젝션/XSS가 원천 방어되는 공통 라이브러리** | Secure Defaults |
| **피어 코드 리뷰** | 비즈니스 로직 결함 및 **권한 인가 우회를 인적 교차 검증** | Logic Review |
| **SAST 정적 분석기** | 소스코드 전수 검사로 **하드코딩 키, 미검증 입력값 자동 적발** | Static Scan |
| **SCA 분석기** | 오픈소스 의존성 라이브러리의 **CVE 취약점 및 공급망 위험 검사** | Dependency Scan|
| **CI/CD Quality Gate** | 정의된 보안 임계치 미달 시 **빌드/배포를 자동 차단** | Quality Gate |

#### 한줄 요약
- 표준 가이드, 안전 기본값 라이브러리, 피어 리뷰, SAST/SCA 스캐너, CI/CD Quality Gate가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **KISA 소프트웨어 개발보안 7대 항목**: 1. 입력 데이터 검증 및 표현, 2. 보안 기능, 3. 시간 및 상태, 4. 에러 처리, 5. 코드 오류, 6. 캡슐화, 7. API 오용.

</details>

```text
표준 린터 배포, 시큐어 코딩 구현, 피어 리뷰, CI/CD SAST/SCA 검사 및 배포 파이프라인
        │
   1. [표준 규칙 제정] 조직 비즈니스 및 언어에 맞춘 시큐어 코딩 가이드 및 IDE 린터 배포
        │
   2. [시큐어 구현] 개발자가 안전 템플릿(PreparedStatement, DOMPurify)을 적용하여 기능 개발
        │
   3. [피어 리뷰 승인] Git PR 생성 ➔ 동료 개발자가 인가(RBAC) 로직 및 결제 조작 가능성 검증
        │
   4. [CI/CD 자동 검사] 파이프라인이 구동되어 SAST 및 SCA 자동 스캔 집행
        │
   ├─ [Critical 취약점 검출 시] ➔ 빌드 즉각 실패(Fail) 및 개발자에게 수정 권고 피드백
   ▼
5. [Quality Gate 통과 및 배포] 전 항목 검증 통과 ➔ 프로덕션 환경 무결성 배포 완료
```

#### 한줄 요약
- 표준 린터 배포 → 시큐어 코딩 구현 → 피어 리뷰 승인 → CI/CD SAST/SCA 자동 스캔 → Quality Gate 배포 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **피어 코드 리뷰 (Human)** vs **자동 정적/동적 스캔 (Tool)** vs **안전 프레임워크 (Architecture)**.

</details>

| 비교 항목 | 피어 코드 리뷰 (Human Review) | 자동 정적/동적 스캔 (SAST / DAST) | 안전 프레임워크 기본값 (Architecture) |
|:---|:---|:---|:---|
| **핵심 검증 대상** | **비즈니스 로직 오류, 권한 인가 결함** | **문법적 결함(CWE), 취약 함수, 시크릿 노출** | **인젝션, XSS, 세션 설정 결함 원천 소거** |
| **장점 및 특징** | **복잡한 업무 흐름 및 도메인 결함 검증 탁월**| **대규모 소스코드를 초고속 일관되게 전수 검사**| **개발자의 코딩 실수 개입 자체를 구조적 차단** |
| **주요 한계점** | 리뷰어 역량 편차 및 시간/인력 리소스 소모 | 문맥 파악 불가로 인한 오탐(False Positive) | 레거시 시스템 및 특수 커스텀 구현 시 제약 |
| **자동화 수준** | **수동 (사람의 정밀 검토 의존)** | **완전 자동화 (CI/CD 파이프라인 연동)** | **완전 자동화 (프레임워크 런타임 강제)** |
| **SDLC 최적 단계** | **코드 구현 직후 (Pull Request 단계)** | **빌드 및 테스트 단계 (Continuous Testing)** | **아키텍처 설계 및 프레임워크 선정 단계** |

#### 한줄 요약
- 피어 리뷰는 비즈니스 로직 검증, SAST/DAST는 기계적 전수 스캔, 안전 프레임워크는 구조적 결함 소거이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-218 (SSDF)**: 조직 준비, 소프트웨어 보호, 안전 소프트웨어 제작, 취약점 대응 4대 영역을 규정한 미국 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SAST 정적 분석기의 오탐으로 인한 **개발 지연 및 개발팀 반발(피로도 증가)** | **`조직 룰셋 테일러링(Tailoring) 및 안전 기본값 프레임워크(Spring Security)` 배포** | 오탐률 80% 이상 절감 및 조치 수용성 100% 확보 |
| SAST만 맹신하다가 **결제 금액 변조 및 BOLA 비즈니스 로직 우회 취약점이 배포** | **배포 전 `피어 코드 리뷰 의무화 및 비즈니스 로직 특화 통합 테스트 코드` 구현** | 자동화 툴 사각지대인 논리적 인가 결함 100% 차단 |
| 릴리즈 압박으로 승인된 보안 예외 코드가 **방치되어 실제 침해 경로로 악용** | **보안 예외 건에 대해 `30~90일 기한부 만료(TTL) 관리 및 만료 시 재검증` 연동** | 기술 부채 누적을 차단하고 지속적 코드 무결성 유지 |
| 개발자들의 시큐어 코딩 지식 격차로 인한 결함 코드 반복 커밋 | **`IDE 내 실시간 SonarLint 플러그인 연동 및 개발자 핸즈온 실습 교육`** | 코딩 시점 결함 유입 원천 차단 및 품질 향상 |

#### 한줄 요약
- 룰셋 테일러링으로 오탐을 줄이고, 피어 리뷰로 로직을 검증하며, 기한부 TTL로 예외를 관리한다.

## Ⅶ. 결론

- 소프트웨어의 구조적 취약성을 설계 및 구현 단계에서 근원 차단하는 **시큐어 코딩 아키텍처는 DevSecOps 및 공급망 보안의 가장 핵심적인 기초 인프라**이며, 실무 구현 시 **NIST SSDF 기반 표준 가이드 제정, Secure by Default 안전 프레임워크 내재화, 피어 코드 리뷰와 SAST/SCA의 하이브리드 검증, CI/CD Quality Gate를 통한 배포 자동 통제**를 결합하여 무결점 소프트웨어 개발 생태계 완성

#### 한줄 요약
- 시큐어 코딩 가이드는 표준 지침과 안전 프레임워크 및 SAST/피어리뷰 결합을 통해 결함 없는 시큐어 소프트웨어를 완성하는 개발 표준 체계다.
