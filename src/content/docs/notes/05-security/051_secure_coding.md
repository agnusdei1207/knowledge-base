## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **시큐어 코딩(Secure Coding)**: 구현 단계에서 입력•권한•암호•오류•자원 처리 결함을 예방하는 코딩 규칙과 검증 활동을 의미함.

</details>

- 정의/개념: 안전한 구현 규칙과 인적•자동 검증을 결합하여 소스 코드 결함 예방.
- 배경/필요성: 개발자별 임의 구현에 따른 보안 취약점 반복 및 소프트웨어 품질 편차 발생.

#### 한줄 요약

- 공격 입력을 안전하게 처리하는 규칙을 코드와 배포 검사에 넣어 같은 결함이 반복되지 않게 한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **위협 모델(Threat Model)**: 보호 자산•신뢰 경계•공격 경로•통제를 식별해 구현 우선순위를 정하는 분석 기법.
- **안전 기본값(Secure Defaults)**: 별도 설정이 없어도 최소 권한•거부•보호 상태를 적용하는 기본 구성 방식.
- **정적 애플리케이션 보안 시험(Static Application Security Testing, SAST)**: 소스 코드의 취약 패턴을 실행 전에 분석하는 검사 기술.
- **동적 애플리케이션 보안 시험(Dynamic Application Security Testing, DAST)**: 실행 중인 애플리케이션의 취약 동작을 검사하는 진단 기술.
- **배포 게이트(Deployment Gate)**: 필수 보안 검사 기준에 미달한 변경의 배포를 차단하는 통제 매커니즘.

</details>

- **위협 모델**과 반복 결함을 언어•프레임워크별 구현 규칙으로 구체화.
- **안전 기본값**과 안전한 대체 API로 위험한 구현 경로 축소.
- **SAST**•**DAST** 검사 결과의 **배포 게이트** 연계 통제.

#### 한줄 요약

- 사람은 업무 권한과 복합 논리를 살피고 자동 도구는 반복 취약 패턴을 빠짐없이 검사한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **시큐어 코딩 통제 구조(Secure Coding Control Framework)**: 규칙 소유•안전 구현•사람 검토•자동 검증•예외 개선을 하나의 배포 경로로 연결한 통제 체계.

</details>

```text
시큐어 코딩 통제
├─ 가이드 소유자: 규칙 우선순위 결정
├─ 안전 구현•대체 규칙: 구현 기준 제공
├─ 개발•코드 리뷰: 업무 논리 검토
├─ 자동 검증•배포 게이트: 미달 배포 차단
└─ 예외•개선 관리: 보상 통제•만료 관리
```

| 구성요소 | 책임 |
|:---|:---|
| 가이드 소유자 | 위협•결함별 규칙 우선순위 결정 |
| 안전 구현•대체 규칙 | 입력•권한•암호•오류 기준 제공 |
| 개발•코드 리뷰 | 템플릿 적용•업무 논리 검토 |
| 자동 검증•배포 게이트 | **SAST**•**DAST** 미달 배포 차단 |
| 예외•개선 관리 | 보상 통제•담당자•만료 관리 |


#### 한줄 요약

- **시큐어 코딩 통제 구조**에서 개발자는 안전한 템플릿을 쓰고 자동 검사는 기준 미달 배포를 막는다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **코드 리뷰(Code Review)**: 자동 도구가 놓치기 쉬운 업무 권한•복합 논리와 안전 API 적용을 사람이 검토하는 절차.
- **안전 응용 프로그래밍 인터페이스(Secure Application Programming Interface, Secure API)**: 검증된 입력•인증•암호•오류 처리 기능을 제공하는 인터페이스 기술.
- **위협•반복 결함 규칙화(Threat & Defect Rule Patterning)**: 위협 모델과 운영 결함을 구현 가능한 안전 규칙으로 전환하는 과정.
- **안전 API•기본값 구현(Secure API & Defaults Implementation)**: 공통 통제를 안전 API와 기본 구성으로 코드에 적용하는 단계.
- **업무 권한•복합 논리 검토(Business Logic & Authorization Review)**: 자동 검사가 놓치는 업무 맥락과 권한 경로를 사람이 확인하는 활동.
- **SAST•DAST 배포 판정(SAST & DAST Deployment Approval)**: 정적•동적 시험 결과를 기준으로 변경의 배포 가능 여부를 결정하는 절차.
- **예외•운영 결함 반영(Exception & Operational Defect Feedback)**: 승인 예외와 운영 사고를 규칙과 시험 기준 개선에 환류하는 과정.

</details>

```text
1. 위협•반복 결함 규칙화
          |
          v
2. 안전 API•기본값 구현
          |
          v
3. 업무 권한•복합 논리 검토
          |
          v
4. SAST•DAST 배포 판정
          |
          +-- 미달 -- 구현•규칙 보완
          |
          +-- 통과 -- 배포•운영 근거 수집
                              |
                              v
                    5. 예외•운영 결함 반영
```

### 동작 원리

1. **위협•반복 결함 규칙화**: 안전 기본값과 대체 API 기준을 정의해 위협•반복 결함 규칙화 수행.
2. **안전 API•기본값 구현**: 입력•권한•암호•오류 통제를 적용해 안전 API•기본값 구현 완료.
3. **업무 권한•복합 논리 검토**: 자동 검사가 놓친 위험 경로를 코드 리뷰로 확인해 업무 권한•복합 논리 검토.
4. **SAST•DAST 배포 판정**: 자동 검사 기준 미달 변경을 차단하는 SAST•DAST 배포 판정 수행.
5. **예외•운영 결함 반영**: 보상 통제•만료일•운영 사고를 규칙 개선에 반영해 예외•운영 결함 환류.


#### 한줄 요약

- **안전 응용 프로그래밍 인터페이스**로 구현한 코드는 **코드 리뷰**와 자동 검사를 통과해야 배포된다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **시큐어 코딩 통제 선택 기준(Secure Coding Control Selection Criteria)**: 업무 논리는 코드 리뷰, 반복 취약 패턴은 자동 검사, 공통 보안 기능은 프레임워크에 맡기는 판단 기준.

</details>

| 시큐어 코딩 통제 | 가이드•리뷰 | 자동 보안 검사 | 안전 기본값•프레임워크 |
|:---|:---|:---|:---|
| 적용 기준 | 설계•권한•업무 규칙 | 주입•비밀•위험 함수 검사 | 공통 인증•인코딩•오류 처리 |
| 핵심 특징 | **코드 리뷰**의 업무 맥락•논리 판단 | **SAST**•**DAST**의 반복 취약 패턴 검사 | **안전 기본값**으로 위험 구현 경로 축소 |
| 한계 | 숙련도•검토 시간 편차 | 오탐•데이터 흐름 한계 | 프레임워크 외 API•설정 오류 |

#### 한줄 요약

- **시큐어 코딩 통제 선택 기준**으로 사람 검토•자동 검사•안전 프레임워크의 역할을 나눈다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SSDF 1.1(NIST Secure Software Development Framework 1.1)**: 안전한 소프트웨어 개발 관행을 제시하는 미국 국립표준기술연구소 프레임워크에 해당함.
- **ISO/IEC 27034-1(ISO/IEC 27034-1)**: 애플리케이션 보안 관리 개념•절차•통제를 정의하는 국제 표준 규격.
- **예외 만료(Exception Expiration)**: 보상 통제와 담당자를 둔 보안 예외가 재검토 없이 영구화되지 않게 하는 통제 정책.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 개발 단계별 보안 관행이 달라 반복 결함 발생 | **NIST SSDF 1.1** 적용 | 개발•검증•대응의 절차 정렬 |
| 조직과 프로젝트의 앱 보안 책임이 분리 | **ISO/IEC 27034-1** 연계 | 조직•프로젝트의 책임 연결 |
| 배포 검사 우회와 만료 없는 예외로 기술 부채 증가 | **배포 게이트**•**예외 만료** 적용 | 반복 결함과 기술 부채 억제 |

#### 한줄 요약

- 개발자가 문자열 결합 SQL을 만들지 않도록 공통 결제 API 템플릿에 입력 검증과 매개변수 바인딩을 기본 구현한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **시큐어 코딩 운영 기준(Secure Coding Operational Baseline)**: 업무 논리는 코드 리뷰, 반복 패턴은 자동 검사, 예외는 만료와 재승인으로 관리하는 지침.

</details>

- **시큐어 코딩 운영 기준**에 따라 업무 논리는 **코드 리뷰**, 반복 패턴은 **SAST**•**DAST**, 예외는 **예외 만료**•재승인 적용.

#### 한줄 요약

- 안전한 대체 API와 배포 게이트를 기본 경로로 만들고 예외는 만료 시 재검토한다.
