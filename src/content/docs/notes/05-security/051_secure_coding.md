## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **시큐어 코딩(Secure Coding)**: 소프트웨어 개발 생명주기(SDLC)의 구현 단계에서 잠재적인 보안 취약점(입력 검증, 권한 관리, 암호화, 예외 처리 등) 발생을 사전에 예방하는 보안 개발 표준 및 검증 체계.

</details>

- 정의/개념: 개발 단계에서 코드 약점을 제거하는 **시큐어 코딩**
- 배경/필요성: 개인 역량 의존은 **반복 취약점•사후 비용**을 유발

#### 한줄 요약

- 소스 코드 수준의 취약점을 개발 단계에서 정적/동적 검사 및 시큐어 코딩 가이드로 선제 제거함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **위협 모델(Threat Model)**: 보호 자산, 신뢰 경계, 위협 요소 및 공격 경로를 식별하여 보안 요구사항을 수립하는 설계 분석 기법.
- **안전 기본값(Secure Defaults)**: 명시적 설정이 없더라도 최소 권한 및 차단 상태가 적용되도록 제공되는 안전한 프레임워크 기본값.
- **정적 애플리케이션 보안 시험(Static Application Security Testing, SAST)**: 소스 코드를 실행하지 않고 텍스트/AST 구조를 정적 분석하여 잠재 취약점을 스캐닝하는 기술.
- **동적 애플리케이션 보안 시험(Dynamic Application Security Testing, DAST)**: 구동 중인 애플리케이션에 실제 패킷을 전송하여 런타임 보안 취약점을 탐지하는 검사 기술.
- **배포 게이트(Deployment Gate)**: CI/CD 파이프라인 상에서 SAST/DAST 검사 기준을 미충족한 소스 코드 커밋의 프로덕션 배포를 자동 차단하는 차단막.

</details>

- **위협 모델(Threat Model)** 분석과 언어/프레임워크별 표준 시큐어 코딩 가이드 규격화.
- **안전 기본값(Secure Defaults)** 및 검증된 보안 API 템플릿 제공을 통한 인적 오설정 최소화.
- **SAST/DAST** 정적•동적 자동 스캐닝 결과와 **배포 게이트(Deployment Gate)** 결합 통제.

#### 한줄 요약

- 개발 가이드 제시, 안전 API 템플릿 활용 및 SAST/DAST 파이프라인 결합을 통해 소스 무결성을 보장함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **시큐어 코딩 통제 구조(Secure Coding Control Framework)**: 가이드 수립, 시큐어 코딩 구현, 코드 리뷰, SAST/DAST 스캔 및 배포 게이트를 통일한 생명주기 관리 체계.

</details>

```text
시큐어 코딩 통제
├─ 가이드 소유자: 규칙 우선순위 결정
├─ 안전 구현•대체 규칙: 구현 기준 제공
├─ 개발•코드 리뷰: 업무 논리 검토
├─ 자동 검증•배포 게이트: 미달 배포 차단
└─ 예외•개선 관리: 보상 통제•만료 관리
```

| 구성요소 | 책임 |
|:---|:---|
| 가이드 소유자 | 최신 취약점(OWASP Top 10, CWE) 기반 전사 시큐어 코딩 규칙 수립 |
| 안전 구현•대체 규칙 | 입력 검증, 쿼리 바인딩, 세션/암호화 표준 라이브러리 제공 |
| 개발•코드 리뷰 | 피어 코드 리뷰(Peer Review) 기반 비즈니스 로직 및 권한 검증 |
| 자동 검증•배포 게이트 | CI/CD 파이프라인 상에서 **SAST/DAST** 자동 검사 및 배포 통제 |
| 예외•개선 관리 | 보상 통제 심의 및 예외 시한 만료 관리 |

#### 한줄 요약

- 가이드 수립, 시큐어 코딩 구현, 피어 코드 리뷰, 자동 보안 스캐닝 및 배포 게이트를 연계 집행함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **코드 리뷰(Code Review)**: SAST 도구가 적발하기 어려운 비즈니스 로직 결함, 권한 우회 및 보안 API 적절성을 동료 개발자가 정독 검증하는 절차.
- **안전 응용 프로그래밍 인터페이스(Secure API)**: SQLi, XSS 방어가 내재화된 표준 입력검증/쿼리파라미터화 제공 라이브러리.
- **위협•반복 결함 규칙화(Threat & Defect Rule Patterning)**: CTI 및 이전 침해사고 결과를 시큐어 코딩 룰에 재반영하는 단계.
- **안전 API•기본값 구현(Secure API & Defaults Implementation)**: 시큐어 파라미터 쿼리 및 이스케이프 모듈을 구현에 적용하는 단계.
- **업무 권한•복합 논리 검토(Business Logic Review)**: 로직 우회 및 인가 미비점을 피어 리뷰로 검증하는 단계.
- **SAST•DAST 배포 판정(Deployment Gating)**: 정적/동적 보안 분석 기준 통과 여부를 판단하는 단계.
- **예외•운영 결함 반영(Feedback Loop)**: 미탐 결함 및 운영 취약점을 가이드 룰에 차기 반영하는 단계.

</details>

```text
1. 위협•반복 결함 규칙화
          │
          ▼
2. 안전 API•기본값 구현
          │
          ▼
3. 업무 권한•복합 논리 검토
          │
          ▼
4. SAST•DAST 배포 판정
          │
          ├─ 미달 ── 구현•규칙 보완
          │
          └─ 통과 ── 배포•운영 근거 수집
                              │
                              ▼
                    5. 예외•운영 결함 반영
```

### 동작 원리

1. **위협•반복 결함 규칙화**: CWE, OWASP 기준 기반 언어별 가이드 룰 확정.
2. **안전 API•기본값 구현**: 개발자가 검증된 **안전 API(Secure API)** 및 기본값 사용.
3. **업무 권한•복합 논리 검토**: 동료 **코드 리뷰(Code Review)**로 비즈니스 로직 취약점 적발.
4. **SAST•DAST 배포 판정**: CI/CD 상에서 **SAST/DAST** 정적/동적 검사 집행 및 배포 제어.
5. **예외•운영 결함 반영**: 관제/침해 사고 사례를 시큐어 코딩가이드 룰에 재반영.

#### 한줄 요약

- 룰 정의, 시큐어 API 구현, 피어 코드 리뷰, SAST/DAST 배포 판정 및 운영 피드백을 연결 구동함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시큐어 코딩 통제 선택 기준(Secure Coding Control Selection Criteria)**: 로직 검증은 피어 리뷰, 패턴 탐지는 SAST/DAST, 공통 보안 기능은 표준 프레임워크에 분담 적용하는 지침.

</details>

| 시큐어 코딩 통제 | 가이드•리뷰 | 자동 보안 검사 | 안전 기본값•프레임워크 |
|:---|:---|:---|:---|
| 적용 기준 | 설계•권한•업무 규칙 | 주입•비밀•위험 함수 검사 | 공통 인증•인코딩•오류 처리 |
| 핵심 특징 | **코드 리뷰**의 업무 맥락•논리 판단 | **SAST/DAST**의 반복 취약 패턴 검사 | **안전 기본값**으로 위험 구현 경로 축소 |
| 한계 | 리뷰어 숙련도 편차 | 오탐(False Positive) 관리 부담 | 프레임워크 외 예외 코드 발생 |

#### 한줄 요약

- 피어 리뷰의 비즈니스 로직 검증, SAST/DAST의 패턴 스캐닝, 프레임워크의 안전 기본값을 상호 보완 적용함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SSDF 1.1(NIST Secure Software Development Framework 1.1)**: 안전한 소프트웨어 개발 관행(PO, PS, PW, RV)을 정의한 미국 표준 가이드.
- **ISO/IEC 27034-1**: 애플리케이션 보안 통제 및 규격(ONF/ANF)을 정의한 국제 표준.
- **예외 만료(Exception Expiration)**: 보안 예외 신청 건에 대해 기한을 부여하고 만료 시 재검증을 강제하는 관리 통제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 체계적 개발 보안 관행 부재 | **NIST SSDF 1.1** 프레임워크 준수 | SDLC 전 단계 보안 관행 수립 |
| 앱 보안 관리 및 검증 절차 파편화 | **ISO/IEC 27034-1** 국제 표준 적용 | 전사 통합 앱 보안 거버넌스 확보 |
| 취약점 예외의 영구 방치 | **배포 게이트** 및 **예외 만료** 시스템 적용 | 무단 배포 차단 및 예외 관제 무결성 확보 |

#### 한줄 요약

- NIST SSDF 1.1 및 ISO/IEC 27034-1 표준을 준수하고, SAST/DAST를 CI/CD 배포 게이트에 자동 연동함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **시큐어 코딩 운영 기준(Secure Coding Operational Baseline)**: 개발자의 안전 코드 구현, 피어 코드 리뷰, SAST/DAST 게이트 및 예외 시한 관리를 결합한 운용 지침.

</details>

- **시큐어 코딩 운영 기준**을 정립하여 로직 검증은 **코드 리뷰**, 패턴 탐지는 **SAST/DAST**, 기술 부채 방지는 **예외 만료** 및 재심의 적용.

#### 한줄 요약

- 로직은 **코드 리뷰**, 패턴은 **SAST/DAST**로 검증
