## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **위협 모델링**: 시스템•공격•대응을 구조화해 설계 단계의 보안 결정을 지원하는 활동이다.
- **공격 시나리오**: 공격자•사전조건•공격 경로•영향•대응을 연결해 구체화한 위협 서술이다.

</details>

- 정의/개념: 설계 흐름에서 **공격 시나리오**•영향•대응을 도출하는 **위협 모델링**이다.
- 배경/필요성: 구현 후 발견하면 경계•권한 구조의 재설계 비용이 증가한다.

#### 한줄 요약

- 경계별 **공격 시나리오·대응 추적**

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **신원 위조•변조•부인•정보 노출•서비스 거부•권한 상승(Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege, STRIDE)**: 여섯 범주로 위협 누락을 점검하는 분류법이다.
- **양방향 추적**: 위협을 보안 요구•통제•시험•운영 결과에 연결하고 반대 방향에서도 근거를 확인할 수 있게 하는 관리 방식이다.

</details>

- 범위•자산•가정•경계를 공통 분석 기준으로 삼는다.
- **STRIDE**로 설계 요소별 위협 누락을 점검한다.
- 위협과 요구•통제•시험•운영 간 **양방향 추적**이 핵심이다.

#### 한줄 요약

- STRIDE 이름을 체크하지 말고 공격자•사전조건•경로•영향이 있는 시나리오로 작성하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **데이터 흐름도(Data Flow Diagram, DFD)**: 주체•프로세스•저장소•정보 흐름을 표현한 도식이다.
- **신뢰 경계**: 데이터나 실행 주체가 이동할 때 정책•권한•신뢰 수준이 달라지는 지점이다.

</details>

```text
위협 모델
├─ 범위•자산•가정
├─ DFD•신뢰 경계
├─ 공격자•STRIDE 시나리오
├─ 위험•대응•잔여위험
└─ 보안 요구•시험•추적
```

가지의 의미: 설계 경계에서 위협을 도출해 대응•시험까지 추적하는 정적 구성이다.

| 구성요소 | 책임 |
|:---|:---|
| 범위•자산•가정 | 버전•환경•의존성•전제 |
| DFD•신뢰 경계 | **DFD**와 **신뢰 경계** |
| 공격자•STRIDE 시나리오 | 능력•조건•경로•영향 |
| 위험•대응•잔여위험 | 회피•완화•이전•수용 |
| 보안 요구•시험•추적 | 소유자•검증•변경 이력 |

#### 한줄 요약

- 위협별 **소유자·대응·검증 연결**

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **잔여위험**: 통제를 적용한 뒤에도 남아 위험 책임자가 근거를 검토•승인해야 하는 위험이다.
- **모델 갱신**: 새 인터페이스•데이터 흐름•운영 사건을 반영해 경계와 위협, 기존 대응의 유효성을 다시 검토하는 활동이다.
- **범위•자산•가정 정의**: 보호 목표•환경•의존성과 분석 경계를 확정하는 단계이다.
- **DFD•신뢰 경계 분해**: 주체•처리•저장소•흐름과 정책 변화 지점을 표현하는 단계이다.
- **STRIDE•공격지식 위협 식별**: 위협 범주와 공격 지식으로 시나리오를 도출하는 단계이다.
- **가능성•영향•대응 검증**: 위험 근거와 보안 요구•설계•시험을 연결하는 단계이다.
- **잔여위험 승인•갱신 조건 결정**: 남은 위험의 책임 승인과 모델 재검토 조건을 정하는 단계이다.

</details>

```text
시스템 설계•보호 대상
          │
          ▼
1. 범위·자산·가정 정의
          │
          ▼
2. DFD·신뢰 경계 분해
          │
          ▼
3. STRIDE·공격지식 위협 식별
          │
          ▼
4. 가능성·영향·대응 검증
          │
          ▼
5. 잔여위험 승인·갱신 조건 결정
          │
          ▼
  위협 모델 결과 반영
```

### 동작 원리

1. **범위·자산·가정 정의**: 보호 목표 확정
2. **DFD·신뢰 경계 분해**: 주체·처리·흐름 작성
3. **STRIDE·공격지식 위협 식별**: 시나리오 도출
4. **가능성·영향·대응 검증**: 요구·시험 연결
5. **잔여위험 승인·갱신 조건 결정**: 책임·재검토 설정

#### 한줄 요약

- 새 API·흐름마다 **위협 모델 갱신**

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **피해•재현성•악용성•영향 사용자•발견성(Damage, Reproducibility, Exploitability, Affected Users, Discoverability, DREAD)**: 다섯 평가 축으로 위험 순위를 참고하는 기법이다.
- **공격 트리**: 공격 목표를 달성하는 조건과 대체 경로를 계층적으로 분해하는 분석 기법이다.

</details>

| 위협 분석 기법 | STRIDE | DREAD | 공격 트리 |
|:---|:---|:---|:---|
| 적용 기준 | DFD별 위협 누락 감소 | 팀 내 우선순위 참고 | 다중 경로•전제조건 분석 |
| 핵심 특징 | **STRIDE** 여섯 범주 | **DREAD** 다섯 평가 축 | **공격 트리** 조건 분해 |
| 한계 | 경로•우선순위 별도 필요 | 척도•평가자 편차 | 공격 경로 조합 증가 |

> 요약: STRIDE 식별 후 근거 기반 위험평가를 별도 수행하는 것이 핵심이다.

#### 한줄 요약

- STRIDE는 무엇이 잘못될지, 공격 트리는 어떻게 도달할지, DREAD는 순서 참고에 도움을 줌이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **보안 개발 수명주기(Security Development Lifecycle, SDL)**: 보안 활동을 개발 수명주기에 통합하는 방법이다.
- **Microsoft SDL**: STRIDE 위협 식별을 포함한 Microsoft 개발 지침이다.
- **개방형 웹 응용 보안 프로젝트(Open Worldwide Application Security Project, OWASP)**: 웹 응용 보안 공개 프로젝트이다.
- **OWASP Threat Modeling**: 범위•위협•대응•충분성을 묻는 접근법이다.
- **MITRE**: 공개 사이버보안 지식체계를 운영하는 비영리기관이다.
- **공통 공격 패턴 열거 및 분류(Common Attack Pattern Enumeration and Classification, CAPEC)**: 공격 패턴을 구조화한 공개 지식기반이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 설계 요소별 위협 식별 | **SDL**과 **Microsoft SDL** 적용 | 위협 누락 감소 |
| 반복 가능한 모델링 과정 | **OWASP**의 **OWASP Threat Modeling** 적용 | 충분성 점검 |
| 구체 공격 시나리오 | **MITRE**의 **CAPEC** 연계 | 완화 보강 |

#### 한줄 요약

- 결제 API의 DFD와 신뢰 경계를 작성하고 STRIDE 위협을 인증•무결성•감사•가용성 시험까지 추적한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **위협 추적성**: 공격 시나리오를 보안 요구•통제•시험•운영 결과와 양방향으로 연결하는 성질이다.
- **위험 처리**: 고영향 위협은 회피•완화하고 남은 위험은 책임자가 승인하는 의사결정이다.

</details>

- **위협 추적성**과 **위험 처리**에 따라 고영향 위협은 회피•완화하고 통제 후 잔여위험만 승인한다.

#### 한줄 요약

- 위협 목록 수보다 설계를 바꾸고 남은 위험을 근거로 설명할 수 있어야 한다.
