## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **위협 헌팅(Threat Hunting)**: 보안 솔루션의 자동 경보(Alert)가 발생하지 않은 상태에서도, 조직 내부망에 이미 지능형 위협 행위자(APT)가 침투하여 은닉 체류 중이라는 **침해 전제(Assume Breach)** 가정 하에 보안 분석가가 가설(Hypothesis)을 수립하고 전사 엔드포인트/네트워크 텔레메트리 데이터를 능동적으로 정밀 분석하여 미탐지된 위협을 발굴하는 선제적 수색 활동.
- **침해 전제(Assume Breach)**: 모든 경계 방어선은 이미 우회되었으며, 내부 시스템 어딘가에 공격자가 정상 권한으로 위장해 활동 중이라는 전제하에 보안 통제를 설계하는 제로 트러스트 핵심 철학.

</details>

- 정의/개념: CTI 위협 인텔리전스 및 MITRE ATT&CK 기반 **가설 수립 $\rightarrow$ 텔레메트리 질의 및 피벗(Pivot) $\rightarrow$ 침해 지표/행위 확정 $\rightarrow$ 탐지 공학 환류(Detection Engineering)** 로 이어지는 **반복적 능동 위협 발굴 및 방어 고도화 프레임워크**
- 배경/필요성: 기존 SIEM/IPS/AV의 수동적 시그니처 매칭 방식으로는 정상 관리 도구(LOLBins)나 유효한 자격증명을 도용하여 은닉 체류하는 APT 공격의 장기 체류 시간(Dwell Time)을 단축할 수 없는 한계를 극복할 요구

#### 한줄 요약
- 침해를 전제하고 가설을 수립하여 텔레메트리 데이터를 능동 분석하고 발굴된 패턴을 자동 탐지 룰로 환류한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **피벗 분석(Pivot Analysis)**: 단일 이상 징후(예: 특정 PowerShell 프로세스의 비정상 인자값)를 기준점으로 삼아, 해당 프로세스를 실행한 상위 부모 프로세스, 실행 사용자 계정, 연결된 외부 C2 IP, 동일 행위를 수행한 타 엔드포인트 목록으로 꼬리를 물고 질의를 확장하는 다차원 연관 추적 기법.
- **탐지 공학 환류(Detection Engineering Feedback Loop)**: 헌팅 활동을 통해 수동으로 밝혀낸 공격 기법과 패턴을 일회성 조치로 끝내지 않고, Sigma/YARA-L 기반의 지속적 자동화 탐지 규칙(Rule)으로 변환하여 SIEM/EDR에 영구 배포하는 선순환 엔지니어링 프로세스.

</details>

- **가설 기반 능동적 수색 (Hypothesis-Driven)**: 수동적 알람 수신이 아닌 CTI와 위협 모델에 근거한 구체적 가설 중심 수색
- **다차원 텔레메트리 피벗팅 (Multi-Dimensional Pivoting)**: 엔드포인트(EDR), 네트워크(NDR), 인증(IAM) 데이터를 상호 결합 추적
- **선순환 탐지 성숙도 고도화**: 헌팅 결과물을 보안 탐지 룰로 코드화(Detection as Code)하여 관제 센터의 미탐 영역 영구 소거

#### 한줄 요약
- 가설 기반 능동 수색, 다차원 텔레메트리 피벗팅, 탐지 공학 환류(Detection as Code)를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **사냥 성숙도 모델(Hunting Maturity Model, HMM)**: 조직의 위협 헌팅 역량을 레벨 0(초기/수동적 알람 대응)부터 레벨 4(선도/자동화된 텔레메트리 수집 및 전담 헌팅팀의 지속적 탐지 공학 환류)까지 5단계로 정의한 성숙도 평가 프레임워크.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 위협 인텔리전스 (CTI) & MITRE ATT&CK ]                             │
│  └─ 가설 수립: "최근 APT 그룹이 정상 Certutil을 악용해 C2와 통신할 것이다" │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 전사 텔레메트리 빅데이터 저장소 (Telemetry Lake) ]                 │
│  ├─ EDR (Sysmon 프로세스 트리, 파일 생성, 레지스트리 수정 로그)         │
│  ├─ NDR (Zeek 네트워크 메타데이터, DNS 질의, 비정상 포트 통신)          │
│  └─ IdP (Active Directory Kerberos 인증, MFA 이상 징후)                 │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (3. 다차원 상관 질의 및 이상 징후 포착)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 피벗팅 및 위협 행위 분석 (Pivoting Engine) ]                        │
│  └─ 단서 식별 ➔ 부모/자식 프로세스 추적 ➔ 동일 서브넷 감염 호스트 전수 조사 │
└──────────────────┬──────────────────────────────────┬───────────────────┘
                   │ (4. 침해 확정 시)                │ (5. 신규 패턴 발견 시)
                   ▼                                  ▼
┌──────────────────────────────────────┐┌──────────────────────────────────────┐
│ [ 4. 사고대응팀 (CSIRT) 긴급 이관 ]  ││ [ 5. 탐지 공학 환류 (Detection Eng) ]│
│  └─ 감염 호스트 네트워크 격리/정화   ││  └─ Sigma 탐지 룰셋 작성 ➔ SIEM 배포 │
└──────────────────────────────────────┘└──────────────────────────────────────┘
```

선의 의미: CTI 기반 가설을 수립하고 텔레메트리 레이크에서 피벗 추적을 수행하여 침해 호스트를 격리하고 신규 패턴을 자동 탐지 룰로 환류하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **가설 수립 엔진** | 최신 CTI 보고서와 ATT&CK TTP를 바탕으로 검증 및 반증 가능한 분석 명제 정의 | Hypothesis |
| **텔레메트리 레이크** | 전사 엔드포인트(EDR), 네트워크(NDR), 클라우드 로그를 실시간 수집 및 중앙 인덱싱 | Data Lake |
| **피벗팅 분석기** | 특정 의심 지표로부터 연관된 프로세스 계통도, 통신 IP, 사용자 세션을 확장 질의 | Pivot Engine |
| **CSIRT 긴급 대응반**| 헌팅을 통해 확정된 침해 호스트를 즉시 네트워크 격리하고 악성 아티팩트 정화 | Incident Response |
| **탐지 공학 환류 파이프라인**| 분석가가 도출한 헌팅 쿼리를 자동화된 실시간 SIEM/EDR 탐지 규칙으로 변환 배포 | Detection as Code |

#### 한줄 요약
- 가설 수립기, 텔레메트리 레이크, 피벗팅 분석기, CSIRT 대응반, 탐지 공학 환류 파이프라인이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **가설의 반증 가능성(Falsifiability)**: 헌팅 가설을 수립할 때 분석가의 확증 편향을 방지하기 위해, "어떠한 데이터가 관측되면 이 가설이 틀렸다고 판단할 것인가"라는 반증 조건을 사전에 정의하는 과학적 수색 방법론.

</details>

```text
1. [가설 수립] CTI 위협 리포트를 기반으로 구체적 공격 행위 가설 및 반증(Falsification) 조건 정의
            │
            ▼
2. [데이터 질의] EDR 텔레메트리 저장소에 KQL/SPL 쿼리를 실행하여 가설에 부합하는 이상 행위 레코드 추출
            │
            ▼
3. [피벗 연관 추적] 식별된 의심 프로세스(T1059)를 기준으로 네트워크 연결 IP 및 부모 프로세스 꼬리물기 추적
            │
            ├─ [정상 관리자의 합법적 작업으로 확인(반증)] ➔ 가설 기각 및 분석 종료
            ▼
4. [침해 행위 확정] 오탐을 배제하고 악의적 APT 침해로 최종 확정 ➔ CSIRT로 감염 호스트 목록 즉각 인계 및 격리
            │
            ▼
5. [탐지 공학 환류] 수동 질의 쿼리를 Sigma 룰로 표준화하여 SIEM 및 EDR에 상시 자동 탐지 룰로 배포
```

**동작 원리**

1. **지식 기반 가설화**: "외부에서 유입된 스크립트가 WMI를 통해 지속성을 생성했을 것이다" 명제 도출
2. **패턴 헌팅 실행**: `ProcessName == "wmic.exe"` 및 의심스러운 커맨드라인 매개변수 필터링
3. **영향도 다차원 전개**: 해당 WMIC 프로세스가 접촉한 도메인 컨트롤러 및 공유 폴더 전수 검사
4. **신속한 격리 조치**: 피해 확산을 차단하기 위해 EDR 원격 에이전트를 통한 호스트 네트워크 차단
5. **지속 가능한 보안 자산화**: 수동 헌팅 결과를 자동화 관제 룰셋으로 흡수하여 탐지 공백 영구 축소

#### 한줄 요약
- 가설/반증 수립, 텔레메트리 질의, 피벗 연관 추적, 침해 확정 및 격리, 탐지 공학 환류 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **위협 헌팅 3대 접근 방식 비교**: 단순 침해 지표(IoC) 기반 헌팅, 행위 패턴(TTP) 기반 헌팅, 통계적 이상치(Anomaly) 기반 헌팅의 비교.

</details>

| 비교 항목 | 침해 지표 기반 (IoC-Driven) | 행위 패턴 기반 (TTP-Driven) | 이상치 통계 기반 (Anomaly-Driven) |
|:---|:---|:---|:---|
| **수색의 기준점** | **외부 CTI에서 제공된 IP, 해시, 도메인**| **MITRE ATT&CK 공격 기법(T-ID)** | **정상 베이스라인(Baseline) 대비 통계 편차** |
| **분석 난이도** | **낮음 (단순 문자열/해시 일치 검색)** | **중간~높음 (프로세스 계통도 및 맥락 분석)**| **높음 (머신러닝 알고리즘 및 노이즈 제거)** |
| **공격자 우회 저항성**| **취약 (공격자가 IP/도메인 변경 시 무력화)**| **매우 높음 (본질적 도구 악용 행위 추적)** | **높음 (사전 정의되지 않은 제로데이 식별)** |
| **주요 적용 사례** | 긴급 보안 권고문 발행 시 내부 유입 확인 | **LotL(LOLBins) 정상 도구 악용 수색** | **심야 시간대 대용량 데이터 전송(Outlier) 식별**|

#### 한줄 요약
- IoC 기반은 단순 해시 검색, TTP 기반은 공격자 본질 행위 수색, Anomaly 기반은 통계 이상치 분석이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **허니토큰(Honeytoken / 디셉션 기술)**: 공격자가 탈취하기 쉬운 위치(엔드포인트 레지스트리, 메모리)에 매력적인 가짜 관리자 자격증명(가짜 AWS API Key, 가짜 도메인 관리자 계정)을 미끼로 배치하여, 해당 토큰에 접근하는 주체를 즉각 100% 신뢰도로 탐지하는 기만 보안 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 헌팅을 통해 은닉 위협을 격리했으나 **유사 공격 발생 시 동일한 수동 분석을 반복하는 비효율** | **헌팅 완료 즉시 Sigma 표준 탐지 룰로 변환하여 SIEM/EDR에 배포하는 탐지 공학 환류** 강제 | 수동 헌팅의 자동화 자산화 및 동일 공격 재침투 시 실시간 차단 |
| 분석가가 가설에 부합하는 데이터만 선택적으로 신뢰하여 **정상 작업을 해킹으로 오판하는 확증 편향** | **가설 수립 시 명확한 반증 조건(Falsification Criteria) 사전 명시 및 피어 리뷰** 의무화 | 분석가의 주관적 오판 방지 및 불필요한 관제 리소스 낭비 원천 차단 |
| 지능형 공격자가 완벽히 정상 관리자 계정으로 위장하여 **텔레메트리 헌팅으로도 식별 불가한 사각지대** | **엔드포인트 및 디렉터리 서비스 내 가짜 미끼 자격증명(Honeytoken/Deception) 분산 배치** | 정상 위장 공격자의 미끼 접근 즉각 포착 및 제로 펄스 포지티브 탐지 달성 |

#### 한줄 요약
- 탐지 공학 환류로 자동화하고, 반증 조건으로 확증 편향을 막으며, 허니토큰으로 은닉 계정을 유인 포착한다.

## Ⅶ. 결론

- 수동적 경보 대응의 한계를 넘어 지능형 은닉 위협을 선제적으로 무력화하는 **위협 헌팅(Threat Hunting) 아키텍처**는 침해 전제(Assume Breach) 보안 패러다임의 핵심 실행 체계이며, 실무 구현 시 **MITRE ATT&CK 기반 TTP 가설 수립**, **전사 텔레메트리 레이크 기반 다차원 피벗팅**, **탐지 공학(Detection as Code) 환류 파이프라인 및 허니토큰 디셉션 연동**을 결합하여 조직의 사이버 레질리언스를 지속적으로 고도화하는 능동 방어 환경을 완성

#### 한줄 요약
- 침해 전제 가설 수립과 텔레메트리 피벗팅 및 탐지 공학 환류를 통해 은닉 위협을 선제 격리하고 방어망을 고도화한다.
