## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Threat Hunting (위협 헌팅)**: 침해 전제(Assume Breach) 하에 분석가가 가설을 수립하고 전사 텔레메트리를 능동 수색하여 미탐지된 은닉 위협을 발굴하는 활동.
- **Assume Breach (침해 전제)**: 이미 내부망에 공격자가 잠복해 있다는 전제하에 능동적 탐지와 격리를 수행하는 보안 철학.

</details>

- 정의/개념: 침해 전제(Assume Breach) 하에 가설을 수립하고 전사 텔레메트리를 능동 수색하여 **은닉 위협을 격리하고 탐지 룰로 환류하는 선제적 위협 수색 기술**
- 배경/필요성: 시그니처 보안 장비의 경보 대기 수동 관제로 인한 **알람 피로도 및 정상 도구(LOLBins) 악용 은닉 위협에 대한 수개월 잠복(Dwell Time) 방치**

#### 한줄 요약
- 가설 기반 능동 수색과 텔레메트리 피벗팅을 통해 시스템 내 은닉 위협을 조기 발굴하고 격리한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Hypothesis-Driven (가설 기반 수색)**: CTI와 ATT&CK TTP를 바탕으로 검증 가능한 공격 시나리오를 명제화하여 수색 범위를 정밀 타깃팅하는 기법.
- **Pivot (피벗팅)**: 단일 의심 프로세스나 IP를 기준으로 연관된 부모 프로세스, 네트워크 세션, 사용자 계정으로 조사 범위를 방사형으로 확장하는 분석 기법.

</details>

- **침해 전제(Assume Breach) 기반 능동성**: 자동 경보가 없어도 **공격자가 이미 내부에 잠복해 있다는 가정하에 선제적 조사 착수**
- **반증 가능한 가설(Hypothesis) 중심 수색**: CTI 및 TTP 지식을 결합하여 **명확한 공격 시나리오와 반증 조건을 정의하고 데이터 질의**
- **탐지 공학(Detection Engineering) 환류 체계**: 헌팅을 통해 발굴된 신규 공격 패턴을 **Sigma 표준 룰로 변환하여 SIEM/EDR에 영구 자산화**

#### 한줄 요약
- 침해 전제 기반 능동성, 반증 가능한 가설 중심 수색, 탐지 공학(Detection as Code) 환류를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Sigma**: 특정 SIEM 벤더에 종속되지 않는 범용 YAML 기반 오픈소스 보안 탐지 시그니처 표준 포맷.

</details>

```text
[가설 기반 위협 헌팅 및 탐지 공학 환류 아키텍처]
|-- 1. Threat Intel / ATT&CK (CTI 기반 가설 및 반증 조건 수립)
`-- 2. Telemetry Lake (전사 EDR, NDR, Cloud 로그 중앙 집결)
`-- 3. Pivot Analysis Engine (프로세스 트리 및 계정 상관 피벗팅)
|   |-- [침해 확정 시] ──▶ 4. CSIRT Incident Response (감염 호스트 네트워크 원격 격리)
|   `-- [신규 패턴 발견 시] ──▶ 5. Detection Engineering (Sigma 룰 작성 -> SIEM 자동 탐지 배포)
```

선의 의미: CTI 기반 가설을 수립하고 텔레메트리 레이크에서 피벗 추적을 수행하여 침해 호스트를 격리하고 신규 패턴을 자동 탐지 룰로 환류하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **가설 수립 엔진** | CTI 보고서와 ATT&CK TTP를 바탕으로 **검증 및 반증 가능한 분석 명제 정의** | Hypothesis |
| **텔레메트리 레이크**| 전사 EDR, NDR, 클라우드 로그를 **실시간 수집 및 중앙 인덱싱 저장** | Data Lake |
| **피벗팅 분석기** | 특정 의심 지표로부터 **연관된 프로세스 계통도, 통신 IP, 세션 확장 질의** | Pivot Engine |
| **CSIRT 긴급 대응반**| 헌팅으로 확정된 침해 호스트를 **즉시 네트워크 격리하고 악성 아티팩트 정화** | Incident Resp |
| **탐지 공학 환류 모듈**| 분석가가 도출한 헌팅 쿼리를 **자동화된 실시간 SIEM 탐지 규칙으로 변환 배포** | Detection as Code|

#### 한줄 요약
- 가설 수립기, 텔레메트리 레이크, 피벗팅 분석기, CSIRT 대응반, 탐지 공학 환류 모듈이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Falsifiability (반증 가능성)**: 분석가의 확증 편향을 방지하기 위해 가설이 틀렸음을 증명하는 정상 작업 조건을 사전에 정의하는 과학적 수색 원칙.

</details>

```text
가설 수립, 텔레메트리 질의, 피벗 연관 추적 및 탐지 공학 환류 파이프라인
        │
   1. [가설 수립] CTI 리포트를 기반으로 구체적 공격 행위 가설 및 반증(Falsification) 조건 정의
        │
   2. [데이터 질의] EDR 텔레메트리 저장소에 KQL/SPL 쿼리를 실행하여 가설 부합 레코드 추출
        │
   3. [피벗 연관 추적] 식별된 의심 프로세스(T1059)를 기준으로 네트워크 연결 IP 및 부모 프로세스 추적
        │
   ├─ [정상 관리자의 합법적 작업 확인(반증)] ➔ 가설 기각 및 분석 종료
   ▼
4. [침해 행위 확정] 오탐을 배제하고 침해로 최종 확정 ➔ CSIRT로 감염 호스트 목록 인계 및 격리
        │
   ▼
5. [탐지 공학 환류] 수동 질의 쿼리를 Sigma 룰로 표준화하여 SIEM 및 EDR에 상시 자동 룰로 배포
```

#### 한줄 요약
- 가설/반증 수립 → 텔레메트리 질의 → 피벗 연관 추적 → 침해 확정 및 격리 → 탐지 공학 환류 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **침해 지표 기반 (IoC)** vs **행위 패턴 기반 (TTP)** vs **이상치 통계 기반 (Anomaly)**.

</details>

| 비교 항목 | 침해 지표 기반 (IoC-Driven) | 행위 패턴 기반 (TTP-Driven) | 이상치 통계 기반 (Anomaly-Driven) |
|:---|:---|:---|:---|
| **수색의 기준점** | **외부 CTI에서 제공된 IP, 해시, 도메인**| **MITRE ATT&CK 공격 기법(T-ID)** | **정상 베이스라인(Baseline) 대비 통계 편차** |
| **분석 난이도** | **낮음 (단순 문자열/해시 일치 검색)** | **중간~높음 (프로세스 계통도 및 맥락 분석)**| **높음 (머신러닝 알고리즘 및 노이즈 제거)** |
| **공격자 우회 저항성**| **취약 (공격자가 IP/도메인 변경 시 무력화)**| **매우 높음 (본질적 도구 악용 행위 추적)** | **높음 (사전 정의되지 않은 제로데이 식별)** |
| **주요 적용 사례** | 긴급 보안 권고문 발행 시 내부 유입 확인 | **LotL(LOLBins) 정상 도구 악용 수색** | **심야 시간대 대용량 데이터 전송(Outlier) 식별**|

#### 한줄 요약
- IoC 기반은 단순 해시 검색, TTP 기반은 공격자 본질 행위 수색, Anomaly 기반은 통계 이상치 분석이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Honeytoken (허니토큰)**: 레지스트리나 메모리에 가짜 관리자 자격증명을 미끼로 심어두고 이에 접근하는 은닉 공격자를 즉각 포착하는 디셉션 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 헌팅 후 유사 공격 발생 시 **동일한 수동 분석을 반복하는 리소스 낭비** | **헌팅 완료 즉시 `Sigma 표준 룰로 변환하여 SIEM/EDR에 배포하는 탐지 공학 환류`** | 수동 헌팅의 자동화 자산화 및 동일 공격 실시간 차단 |
| 분석가가 가설에 부합하는 데이터만 신뢰하여 **정상 작업을 침해로 오판하는 확증 편향** | **가설 수립 시 `명확한 반증 조건(Falsification Criteria) 사전 명시 및 피어 리뷰`** | 분석가의 주관적 오판 방지 및 관제 효율화 |
| 지능형 공격자가 완벽히 정상 계정으로 위장하여 **텔레메트리 헌팅으로도 식별 불가** | **엔드포인트 및 디렉터리 서비스 내 `가짜 미끼 자격증명(Honeytoken) 분산 배치`** | 정상 위장 공격자의 미끼 접근 즉각 포착 및 100% 탐지 |
| 방대한 엔드포인트 텔레메트리 데이터로 인한 쿼리 응답 지연 | **`핫/웜/콜드 스토리지 티어링 및 분산 빅데이터 인덱싱(Elastic/OpenSearch)`** | 수십 테라바이트 텔레메트리 대상 초 단위 고속 검색 보장 |

#### 한줄 요약
- 탐지 공학 환류로 자동화하고, 반증 조건으로 확증 편향을 막으며, 허니토큰으로 은닉 계정을 유인 포착한다.

## Ⅶ. 결론

- 수동적 경보 대응의 한계를 넘어 지능형 은닉 위협을 선제적으로 무력화하는 **위협 헌팅(Threat Hunting) 아키텍처는 침해 전제(Assume Breach) 보안 패러다임의 핵심 실행 체계**이며, 실무 구현 시 **MITRE ATT&CK 기반 TTP 가설 수립, 전사 텔레메트리 레이크 기반 다차원 피벗팅, 탐지 공학(Detection as Code) 환류 파이프라인 및 허니토큰 디셉션 연동**을 결합하여 조직의 사이버 레질리언스를 지속적으로 고도화하는 능동 방어 환경 완성

#### 한줄 요약
- 위협 헌팅은 침해 전제 가설 수립과 텔레메트리 피벗팅 및 탐지 공학 환류를 통해 은닉 위협을 선제 격리하고 방어망을 고도화하는 능동 보안 체계다.
