## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **망분리•망연계**: 보안영역의 직접 통신을 차단하고 승인된 정보만 검사•중계•감사하는 통제이다.

</details>

- 정의/개념: 보안영역 사이의 승인된 정보만 검사•중계하는 **망분리•망연계**이다.
- 배경/필요성: 완전 단절만으로는 필요한 망 간 업무 데이터를 교환할 수 없다.

#### 한줄 요약

- 두 망 사이에 필요한 물건만 검사하고 기록해 통과시키는 검문소를 둠이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **세션 종단**: 중계 장치가 양쪽 연결을 각각 끝내 분리된 망의 직접 통신을 막는 방식이다.
- **CDR(Content Disarm and Reconstruction)**: 실행 요소를 제거해 파일을 재구성하는 기술이다.
- **DLP(Data Loss Prevention)**: 민감정보 유출을 탐지•차단하는 통제이다.

</details>

- 데이터•방향•시간을 업무별 최소 범위로 허용한다.
- **세션 종단**으로 직접 연결을 차단한다.
- **CDR**•**DLP**와 악성코드 검사를 통합한다.

#### 한줄 요약

- 파일 확장자만 보지 않고 내부 매크로•객체•민감정보와 실제 목적지까지 검사하는 것이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **무결성 전송**: 대상•순서•해시•재전송 정보를 검사해 오배송•변조•중복을 막는 기능이다.
- **능동 콘텐츠•민감정보 검사**: CDR과 DLP로 위험 내용을 확인하는 통제이다.

</details>

```text
망분리•망연계 통제
├─ 업무•반출입 승인
├─ 세션 종단•중계 제어
├─ 악성코드•CDR•DLP
├─ 대상•순서•무결성 전송
└─ 승인•검사•전송 감사
```

| 구성요소 | 책임 |
|:---|:---|
| 업무•반출입 승인 | 주체•자료•목적•목적지 판정 |
| 세션 종단•중계 제어 | 에이전트•프록시로 연결 분리 |
| 악성코드•CDR•DLP | **능동 콘텐츠•민감정보 검사** |
| 대상•순서•무결성 전송 | **무결성 전송**으로 해시•중복 검증 |
| 승인•검사•전송 감사 | 결정•결과•관리 행위 보관 |

#### 한줄 요약

- 송수신망이 직접 대화하지 않고 중계 구간이 내용을 검사한 뒤 별도 연결로 전달하는 것이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **감사 증적**: 승인부터 검사•전송•수신 결과까지 흐름을 재구성할 수 있게 남긴 기록이다.
- **승인된 방향•자료•목적지 확인**: 정책•결재•예외에 따라 허용 전송 범위를 판정하는 단계이다.
- **악성•민감정보•CDR 검사**: 압축•능동 객체•민감정보를 검사해 차단•무해화를 결정하는 단계이다.
- **대상•순서•해시 전송 자료 구성**: 오배송•변조•중복 방지 정보를 전송 자료에 포함하는 단계이다.
- **수신 순서•해시•무결성 검증**: 수신 결과의 순서와 동일성을 확인하는 단계이다.

</details>

```text
주체•자료•목적•목적지 요청
   │
   ▼
1. 승인된 방향•자료•목적지 확인
   ├─ 미승인 ──► 전송 차단
   └─ 승인
        │
        ▼
2. 악성•민감정보•CDR 검사
   ├─ 위험 탐지 ──► 차단•무해화
   └─ 통과
        │
        ▼
3. 대상•순서•해시 전송 자료 구성
   │ 검사된 자료
   ▼
4. 수신 순서•해시•무결성 검증
   │
   ▼
수신 확인•전송 결과
```

### 동작 원리

- **1. 승인된 방향•자료•목적지 확인**: **승인된 방향•자료•목적지 확인**으로 허용 범위를 판정한다.
- **2. 악성•민감정보•CDR 검사**: **악성•민감정보•CDR 검사**로 차단•무해화를 결정한다.
- **3. 대상•순서•해시 전송 자료 구성**: **대상•순서•해시 전송 자료 구성**으로 방지 정보를 생성한다.
- **4. 수신 순서•해시•무결성 검증**: **수신 순서•해시•무결성 검증** 결과를 **감사 증적**으로 남긴다.

#### 한줄 요약

- 누가 어디로 무엇을 왜 보냈는지와 검사•수신 결과를 남겨 사고 흐름을 재구성하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **자료 전송**: 저장 후 파일을 검사•전달하는 방식이다.
- **스트림 연계**: 실시간 세션을 종단•중계하는 방식이다.
- **단방향 전송**: 한 방향 정보 흐름만 허용하는 방식이다.
- **은닉 채널**: 허용 데이터•신호에 비밀 정보를 실어 정책을 우회하는 비인가 통신 경로이다.
- **API(Application Programming Interface) 연계**: 실시간 요청을 프록시에서 종단•중계하는 방식이다.

</details>

| 망연계 방식 | 자료 전송 | 스트림 연계 | 단방향 전송 |
|:---|:---|:---|:---|
| 적용 기준 | 문서•배치 전송 | API•동기 업무 | 로그 수집•정책 배포 |
| 핵심 특징 | **자료 전송**으로 저장 후 전달 | **스트림 연계**와 **API 연계** | **단방향 전송** |
| 한계 | 콘텐츠 검사 우회 | 양쪽 망 확산 | **은닉 채널**•역방향 신호 |

> 요약: 데이터 형태•실시간성•방향에 따라 방식을 선택하는 것이 핵심이다.

#### 한줄 요약

- 데이터 유형 및 트래픽 방향성(파일, 스트리밍, 단방향)에 따라 맞춤 망연계 솔루션을 차등 적용해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **SP(Special Publication)**: NIST가 발행하는 특별간행물이다.
- **AC(Access Control)**: 접근통제 통제군이다.
- **SC(System and Communications Protection)**: 시스템통신보호 통제군이다.
- **NIST SP 800-53 AC-4**: 정보 흐름을 집행하는 통제이다.
- **NIST SP 800-53 SC-7**: 통신 경계를 보호하는 통제이다.
- **SaaS(Software as a Service) 예외**: 외부 클라우드 서비스의 승인된 예외 경로이다.
- **전자금융감독규정 제15조**: 금융회사의 해킹 방지와 내부 업무용 시스템 망분리 등을 규정한 조항이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 흐름 기준이 없으면 승인 자료가 다른 경로로 확산됨 | **NIST**의 **SP**, **AC**, **NIST SP 800-53 AC-4** 적용 | 방향•유형•정책 집행 |
| 양쪽 망 세션이 직접 연결되면 취약점이 전파됨 | **SC**의 **NIST SP 800-53 SC-7** 적용 | 세션 종단•경로 통제 |
| 금융 업무망의 외부 연결은 규정 위반 위험이 있음 | **전자금융감독규정 제15조**와 **SaaS 예외** 준수 | 대체통제 확보 |

#### 한줄 요약

- 외부 파일은 승인•악성코드 검사•CDR을 통과한 경우만 전용 중계가 내부망에 전달하고 이력을 남긴다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **최소 정보 흐름**: 업무에 필요한 데이터•방향•시간•목적지만 허용하는 경계 통제 원칙이다.
- **API 프록시**: 실시간 요청을 종단하고 승인 기능만 중계하는 방식이다.

</details>

- **최소 정보 흐름** 원칙에 따라 문서는 자료 전송, 실시간 연계는 **API 프록시**, 일방 흐름은 단방향 전송을 적용한다.

#### 한줄 요약

- 많이 전달하는 것보다 필요한 데이터만 안전하고 추적 가능하게 전달하는 것이 성공 기준이다.
