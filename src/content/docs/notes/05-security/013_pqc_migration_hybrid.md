## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PQC Migration (양자내성암호 전환)**: 기존 인프라의 RSA/ECC 암호를 NIST FIPS PQC 표준으로 전면 교체하는 체계적 엔지니어링 프로세스.
- **Hybrid Mode (이중 키 교환, NIST SP 800-227)**: 고전 ECDHE와 신규 ML-KEM을 병렬 결합하여 두 알고리즘 중 하나만 안전해도 기밀성을 유지하는 과도기 메커니즘.

</details>

- 정의/개념: CBOM 자산 식별부터 고전(X25519)과 PQC(ML-KEM)를 병렬 결합하는 **하이브리드 운영을 거쳐 순수 PQC로 전환하는 단계적 이행 전략 및 이중 키 교환 기술**
- 배경/필요성: 급진적 PQC 단독 전환 시의 **미검증 알고리즘 결함 위험, 레거시 호환성 단절 및 고전 암호 방치 시의 SNDL 도청 피해**

#### 한줄 요약
- CBOM 식별과 하이브리드 이중 키 교환(Dual-KEM)을 통해 안전하고 단절 없는 PQC 전환을 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **HKDF Combiner (하이브리드 결합기)**: 고전 공유 비밀($SS_{\text{classic}}$)과 양자 공유 비밀($SS_{\text{pqc}}$)을 결합하여 단일 마스터 세션키를 도출하는 암호학적 해시 결합기.
- **Mosca's Theorem (모스카 부등식)**: 데이터 보존 기간($X$)과 전환 소요 기간($Y$)의 합이 양자컴 출현 시점($Z$)보다 크면($X+Y>Z$) 즉시 침해 위험에 노출된다는 정리.

</details>

- **이중 보안 안전망(Dual-Security Shield)**: 고전 암호(FIPS 인증)와 **PQC 암호(양자내성)를 결합하여 단일 알고리즘 취약점 위험 완벽 제거**
- **기존 네트워크 인프라와의 점진적 공존**: TLS 1.3 표준 확장을 활용하여 **PQC 미지원 구형 클라이언트와의 하위 호환성 유지**
- **모스카 부등식 기반 우선순위 전환**: 장기 보존 기밀 데이터를 식별하여 **SNDL 도청 위험이 높은 핵심 트래픽부터 선제 전환**

#### 한줄 요약
- 이중 안전망 제공, 기존 인프라와의 점진적 공존, 모스카 부등식 기반 우선순위 전환을 실현한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Dual-KEM (X25519 + ML-KEM-768)**: 단일 핸드셰이크 내에서 32바이트 X25519 공개키와 1,184바이트 Kyber 공개키를 함께 전송하는 하이브리드 KEM 규격.

</details>

```text
[PQC 하이브리드 키 교환 및 KDF 결합 아키텍처]
|-- Client (1. X25519 pk_c + ML-KEM pk_pqc 병렬 생성 후 ClientHello 전송)
`-- Server (2. 고전 및 양자 KEM 병렬 연산)
    |-- SS_classic = ECDH(sk_c, pk_c) (고전 공유 비밀 도출)
    |-- (c_pqc, SS_pqc) = Encaps(pk_pqc) (양자 KEM 캡슐화)
    `-- Hybrid Combiner: K_master = HKDF-Extract(Salt, SS_classic || SS_pqc || c_pqc)
`-- Client Decapsulation (양자 개인키로 디캡슐화 -> 동일한 K_master 도출 -> AES-GCM 통신)
```

선의 의미: 클라이언트와 서버가 고전 키와 PQC 키를 병렬로 교환하고 HKDF 결합기를 통해 두 공유 비밀을 안전하게 합성하여 단일 마스터 세션키를 생성하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **CBOM 스캐너** | 레거시 암호화 라이브러리, **인증서, 하드코딩 키 식별 및 자산 목록화** | CycloneDX / SPDX |
| **X25519 KEM 모듈** | 기존 FIPS 검증 완료된 **초고속 타원곡선 기반 고전 키 교환 실행** | RFC 7748 |
| **ML-KEM 모듈** | 양자컴퓨터의 쇼어 알고리즘을 방어하는 **모듈 격자 기반 KEM 실행** | NIST FIPS 203 |
| **하이브리드 결합기** | 고전과 PQC 공유 비밀을 **암호학적으로 안전하게 결합하여 세션키 파생** | NIST SP 800-227 |
| **폴백 방어 정책기** | 레거시 암호로의 **비정상적 다운그레이드 시도를 탐지하고 강제 차단** | Policy Engine |

#### 한줄 요약
- CBOM 스캐너, X25519 모듈, ML-KEM 모듈, HKDF 결합기, 폴백 방어 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PQC 전환 4단계**: 1. 식별(CBOM 구축) → 2. 평가(Mosca 위험 분석) → 3. 시범 적용(하이브리드 KEM) → 4. 전면 격리(레거시 차단).

</details>

```text
CBOM 자산 식별, Mosca 평가, 하이브리드 KEM 배포 및 레거시 차단 파이프라인
        │
   1. [CBOM 자산 식별] 전사 인프라 및 소스 코드를 스캔하여 레거시 RSA/ECC 사용 지점 목록화
        │
   2. [Mosca 위험 평가] 기밀 수명 10년 이상의 장기 보존 데이터(SNDL 위협)를 1차 전환 대상으로 지정
        │
   3. [하이브리드 KEM 배포] 백본 API 게이트웨이 및 TLS 1.3 구간에 X25519 + ML-KEM 활성화
        │
   4. [네트워크 호환성 검증] 1KB+ 공개키로 인한 MTU 단편화 및 구형 방화벽 패킷 드롭 여부 모니터링
        │
   ▼
5. [레거시 통신 전면 차단] 전 시스템 PQC 적용 완료 후 레거시 RSA 키 교환을 방화벽에서 완전 차단
```

#### 한줄 요약
- CBOM 식별 → Mosca 위험 평가 → 하이브리드 KEM 배포 → MTU 호환성 검증 → 레거시 완전 차단 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **고전 유지** vs **하이브리드 결합 (과도기)** vs **순수 PQC 단독 (최종 목표)**.

</details>

| 비교 항목 | 고전 암호 유지 (Legacy) | 하이브리드 결합 방식 (Hybrid Mode) | 순수 PQC 단독 전환 (Pure PQC) |
|:---|:---|:---|:---|
| **암호화 구성** | **단일 고전 암호 (RSA / ECDHE)** | **고전(X25519) + 양자(ML-KEM) 병렬 결합** | **100% 단일 PQC 알고리즘 (ML-KEM)** |
| **양자 위협 방어 (SNDL)**| **취약 (양자컴퓨터 출현 시 즉시 해독)**| **완벽 방어 (ML-KEM에 의해 영구 기밀 보장)**| **완벽 방어 (양자내성 수학 난제)** |
| **PQC 수학 결함 위험** | 없음 (고전 수학 검증 완료) | **안전 (PQC 결함 시 고전 암호가 방어)** | 취약 (신규 PQC 알고리즘 결함 시 위험) |
| **네트워크 오버헤드** | 최소 (공개키 32~64 바이트) | 중간 (공개키 약 1.2 KB 수준) | 중간 (공개키 약 1.1 KB 수준) |
| **글로벌 표준화 상태** | 폐기 로드맵 수립 중 | **현재 권고 표준 (Chrome, Cloudflare 채택)**| 2030~2035년 최종 도달 목표 |

#### 한줄 요약
- 고전 유지는 양자 해독에 취약하고, 순수 PQC는 알고리즘 결함 리스크가 있으므로, 과도기에는 하이브리드가 최적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Crypto-Agility Architecture**: 암호 라이브러리를 애플리케이션에 직접 바인딩하지 않고 추상 인터페이스로 래핑하여 무중단 핫스왑을 지원하는 아키텍처.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소스 코드 내 암호 하드코딩으로 인한 **PQC 교체 시 대규모 서비스 중단** | **`OpenSSL 3.0 Provider / JCA 기반 암호 인터페이스 추상화(암호 민첩성)`** | 비즈니스 로직 수정 없이 설정 변경만으로 알고리즘 핫스왑 |
| 네트워크 중간자가 PQC 확장을 변조하여 RSA로 낮추는 **다운그레이드 공격** | **`TLS 1.3 트랜스크립트 서명 강제` 및 서버 상 레거시 폴백 완전 차단** | 취약 고전 암호로의 강제 전환 차단 및 연결 무결성 보장 |
| PQC 키 크기 증가(1.2KB+)로 인한 **구형 방화벽의 비정상 패킷 드롭 장애** | **사전 스테이징 환경에서 `MTU/MSS 실사 및 방화벽 패킷 룰셋 갱신`** | 패킷 손실률 0% 달성 및 레거시 네트워크 장비 공존 보장 |
| 인증서 서명 체인 전환 시 클라이언트 신뢰 저장소 불일치 | **`고전/PQC 이중 서명 인증서(Dual-Signed Certificate)` 발행** | 신구 단말 모두에서 신뢰 경고 없는 무중단 전환 실현 |

#### 한줄 요약
- 암호 민첩성으로 코드 수정을 방지하고, 폴백 차단으로 다운그레이드를 막으며, MTU 검증으로 패킷 드롭을 예방한다.

## Ⅶ. 결론

- 양자 컴퓨팅에 의한 암호학적 위기(Y2Q)에 선제 대응하기 위해 **PQC 마이그레이션 및 하이브리드 전환 아키텍처는 전 세계 정부 및 엔터프라이즈의 표준 가이드라인으로 확립**되었으며, 실무 추진 시 **CBOM 기반의 자산 가시화, X25519+ML-KEM 하이브리드 키 교환의 선제 적용, 엄격한 레거시 폴백 차단 및 암호 민첩성 설계**를 결합하여 단절 없는 무결점 차세대 암호 전환 완성

#### 한줄 요약
- PQC 전환은 CBOM 자산 식별과 하이브리드 KEM 결합 및 암호 민첩성 설계를 통해 안전하고 유연하게 완수해야 한다.
