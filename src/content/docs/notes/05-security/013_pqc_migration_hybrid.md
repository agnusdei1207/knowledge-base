## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PQC 마이그레이션(PQC Migration)**: 기존 엔터프라이즈 인프라에서 운용 중인 취약한 공개키 암호(RSA, ECC)를 NIST 표준 양자내성암호(FIPS 203/204/205)로 전면 교체·전환하는 체계적 엔지니어링 프로세스.
- **하이브리드 암호화 방식(Hybrid Mode / Dual-Key Exchange)**: PQC 알고리즘 도입 초기 안정성을 담보하기 위해, 기존 검증된 고전 알고리즘(ECDHE)과 신규 양자내성 알고리즘(ML-KEM)을 병렬로 동시 실행하여 두 암호체계가 모두 뚫리지 않는 한 완벽한 보안을 보증하는 이중 보호 메커니즘 (NIST SP 800-227).

</details>

- 정의/개념: 자산 식별(CBOM) $\rightarrow$ 위험 평가 $\rightarrow$ **하이브리드 과도기 운영(Dual-KEM/Dual-Signature)** $\rightarrow$ 순수 PQC 단독 전환에 이르는 **단계적 PQC 이행 로드맵** 및 **하이브리드 키 결합 프레임워크**
- 배경/필요성: 신규 PQC 수학 모델의 잠재적 취약점 발견 위험을 완화하고, 고전 암호 인프라와의 완벽한 하위 호환성을 유지하면서 SNDL 도청 공격을 선제 차단할 요구

#### 한줄 요약
- CBOM 기반 자산 식별 후 ECDHE와 ML-KEM을 결합한 하이브리드 방식으로 점진적 양자내성 전환을 달성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **키 결합 함수(Key Combiner / HKDF Combiner)**: 고전 키 교환에서 도출된 공유 비밀($SS_{\text{classic}}$)과 양자내성 KEM에서 도출된 공유 비밀($SS_{\text{pqc}}$)을 결합하여, 두 알고리즘 중 어느 하나라도 안전하면 최종 세션키가 100% 안전함을 수학적으로 보증하는 결합 함수.
- **암호 민첩성(Crypto Agility)**: 암호화 라이브러리와 애플리케이션 비즈니스 로직을 분리(추상화)하여, 설정 파일 변경만으로 암호 알고리즘과 키 길이를 무중단 교체할 수 있는 아키텍처 역량.

</details>

- **이중 보안 보증 (Dual-Security Guarantee)**: 고전 타원곡선(X25519)과 PQC(Kyber768) 중 하나가 암호학적으로 붕괴되어도 전체 기밀성 완벽 유지
- **SNDL 위협 우선순위 기반 단계적 전환**: 장기 기밀성이 요구되는 데이터 전송 채널(KEM)을 1단계로 전환하고, 인증/서명(DSA)은 2단계로 순차 전환
- **레거시 폴백(Fallback) 방어**: 다운그레이드 공격자가 PQC를 배제하고 취약한 구형 RSA로 강제 우회하지 못하도록 엄격한 정책 집행

#### 한줄 요약
- 이중 보안 보증, KEM 우선 단계적 전환, 암호 민첩성 기반 무중단 교체, 레거시 폴백 차단을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IETF X25519Kyber768Draft00**: 클라이언트와 서버가 TLS 1.3 핸드셰이크 시 32바이트 X25519 공개키와 1,184바이트 Kyber768 공개키를 단일 Key Share 확장에 결합하여 전송하는 글로벌 표준 하이브리드 키 교환 규격.

</details>

```text
[ 클라이언트 (Client: Browser / Envoy Proxy) ]
 ├─ 1. X25519 임시 키 쌍 생성 ➔ $pk_{\text{classic}}$
 └─ 2. ML-KEM-768 임시 키 쌍 생성 ➔ $pk_{\text{pqc}}$
           │
           ▼ [ 단일 하이브리드 Key Share 패킷 전송: $pk_{\text{classic}} \parallel pk_{\text{pqc}}$ ]
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [ TLS 1.3 하이브리드 핸드셰이크 전송 구간 (Insecure Public Network) ]                             │
└──────────────────────────────────┬───────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
[ 서버 (TLS Web Server / API Gateway) ]
 ├─ 1. 고전 키 교환 연산 ➔ $SS_{\text{classic}} = \text{ECDH}(sk_{\text{classic}}, pk_{\text{classic}})$
 ├─ 2. 양자 KEM 캡슐화 연산 ➔ $(c_{\text{pqc}}, SS_{\text{pqc}}) = \text{Encaps}(pk_{\text{pqc}})$
 └─ 3. 하이브리드 결합기(HKDF Combiner) 가동:
       $K_{\text{master}} = \text{HKDF-Extract}(\text{Salt}, SS_{\text{classic}} \parallel SS_{\text{pqc}} \parallel c_{\text{pqc}})$
                                   │
                                   ▼ (암호문 캡슐 $c_{\text{pqc}}$ 전송)
                      [ 클라이언트 디캡슐화 및 동일 마스터 세션키 $K_{\text{master}}$ 도출 ]
```

선의 의미: 클라이언트와 서버가 고전 키와 PQC 키를 병렬로 교환하고, HKDF 결합기를 통해 두 공유 비밀을 안전하게 합성하여 단일 마스터 세션키를 생성하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **CBOM 스캐너** | 레거시 암호화 라이브러리(OpenSSL, BouncyCastle), 인증서, 하드코딩 키 식별 | CycloneDX / SPDX |
| **X25519 KEM 모듈** | 기존 FIPS 검증 완료된 초고속 타원곡선 기반 고전 키 교환 실행 | RFC 7748 |
| **ML-KEM 모듈** | 양자컴퓨터의 쇼어 알고리즘 해독을 차단하는 모듈 격자 기반 KEM 실행 | FIPS 203 |
| **하이브리드 결합기** | $SS_{\text{classic}}$과 $SS_{\text{pqc}}$를 암호학적으로 안전하게 결합하여 세션키 파생 | NIST SP 800-227 |
| **폴백 방어 정책기** | 레거시 암호로의 비정상적 다운그레이드 시도를 탐지하고 연결을 강제 차단 | Policy Engine |

#### 한줄 요약
- CBOM 스캐너, X25519 모듈, ML-KEM 모듈, HKDF 결합기, 폴백 방어 엔진이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PQC 전환 4단계 라이프사이클**:
  1. **식별(Discover)**: CBOM을 구축하여 전환 대상 시스템 및 알고리즘 의존성 파악
  2. **위험 평가(Assess)**: 데이터 기밀 유지 요구 기간($X$)과 양자컴 출현 시점($Y$)을 비교하는 Mosca 부등식 분석
  3. **하이브리드 시범 적용(Pilot)**: 핵심 트래픽에 X25519+ML-KEM 하이브리드 모드 배포
  4. **전면 전환 및 격리(Enforce)**: PQC 표준 전면 강제 및 레거시 취약 암호 포트 완전 차단

</details>

```text
1. [식별 단계] 전사 IT 인프라 및 소스 코드 대상 CBOM 자동 스캔 ➔ 레거시 RSA/ECC 사용 지점 100% 식별
            │
            ▼
2. [평가 단계] 기밀 수명 10년 이상의 장기 보존 데이터(SNDL 위협)를 1차 전환 최우선순위로 지정
            │
            ▼
3. [시범 적용] 백본 API 게이트웨이 및 TLS 1.3 구간에 X25519 + ML-KEM 하이브리드 KEM 활성화
            │
            ▼
4. [호환성 검증] 대용량 공개키(1KB+)로 인한 MTU 단편화 및 구형 방화벽 패킷 드롭 여부 모니터링
            │
            ▼
5. [전면 확산] 사내 전 시스템 PQC 적용 완료 ➔ 레거시 RSA 키 교환 통신을 방화벽에서 전면 차단(Enforce)
```

**동작 원리**

1. **인벤토리화**: 정적 코드 분석(SAST) 및 트래픽 스니핑을 통해 조직 내 모든 암호 자산 목록화
2. **Mosca 위험 모델링**: $X(\text{데이터 보존기간}) + Y(\text{PQC 전환 소요기간}) > Z(\text{양자컴 출현 시점})$ 시스템 긴급 지정
3. **하이브리드 배포**: 성능 영향이 적은 하이브리드 KEM을 우선 배포하여 SNDL 공격 무력화
4. **네트워크 버퍼 최적화**: PQC 패킷 크기 증가에 대응하여 TCP MSS 및 버퍼 윈도우 크기 튜닝
5. **보안 게이트웨이 강제**: 인증서 및 TLS 설정에서 구형 암호 스위트를 영구 비활성화

#### 한줄 요약
- CBOM 식별, Mosca 위험 평가, 하이브리드 KEM 배포, MTU 호환성 검증, 레거시 완전 차단 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **PQC 전환 접근 방식 비교**: 고전 암호 단독 유지, 과도기 하이브리드 결합, 최종 PQC 단독 전환의 비교.

</details>

| 비교 항목 | 고전 암호 유지 (Legacy) | 하이브리드 결합 방식 (Hybrid Mode) | 순수 PQC 단독 전환 (Pure PQC) |
|:---|:---|:---|:---|
| **암호화 구성** | **단일 고전 암호 (RSA / ECDHE)** | **고전(X25519) + 양자(ML-KEM) 병렬 결합** | **100% 단일 PQC 알고리즘 (ML-KEM)** |
| **양자 위협 방어 (SNDL)**| **취약 (양자컴퓨터 출현 시 즉시 해독)**| **완벽 방어 (ML-KEM에 의해 영구 기밀 보장)**| **완벽 방어 (양자내성 수학 난제)** |
| **PQC 수학 결함 위험** | 없음 (고전 수학 검증 완료) | **안전 (PQC 결함 시 고전 암호가 방어)** | 취약 (신규 PQC 알고리즘 결함 시 위험) |
| **네트워크 오버헤드** | 최소 (공개키 32~64 바이트) | 중간 (공개키 약 1.2 KB 수준) | 중간 (공개키 약 1.1 KB 수준) |
| **글로벌 표준화 상태** | 폐기 로드맵 수립 중 | **현재 권고 표준 (Chrome, Cloudflare 채택)**| 2030~2035년 최종 도달 목표 |

#### 한줄 요약
- 고전 유지는 양자 해독에 취약하고, 순수 PQC는 알고리즘 결함 리스크가 있으므로, 과도기에는 하이브리드가 최적이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Mosca의 양자 위협 정리(Theorem of Quantum Risk)**:
  - $X$: 보호해야 하는 데이터의 필수 보안 수명 (Security Shelf-Life)
  - $Y$: 인프라를 PQC로 전환하는 데 걸리는 마이그레이션 소요 시간 (Migration Time)
  - $Z$: 범용 양자컴퓨터가 출현하여 기존 암호가 붕괴되는 시점 (Collapse Time)
  - 조건: $X + Y > Z$인 경우, 조직은 이미 데이터 침해 위험 상태(Vulnerable)에 진입한 것으로 판정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소스 코드 내 암호 알고리즘 하드코딩으로 인한 **PQC 교체 시 대규모 서비스 중단 및 재개발** | **JCA/JCE 및 OpenSSL 3.0 Provider 기반 암호 인터페이스 추상화(암호 민첩성)** | 비즈니스 로직 수정 없이 설정 변경만으로 알고리즘 핫스왑 지원 |
| 네트워크 중간자가 PQC 확장을 변조하여 취약한 구형 RSA로 낮추는 **다운그레이드 공격** | **TLS 1.3 트랜스크립트 서명 강제 및 서버 정책 상 레거시 폴백(Fallback) 완전 차단** | 취약 고전 암호로의 강제 전환 차단 및 하이브리드 연결 무결성 보장 |
| PQC 키 크기 증가(1.2KB+)로 인한 **구형 레거시 방화벽/IPS의 비정상 패킷 드롭 장애** | **사전 스테이징 환경에서 PQC 트래픽 MTU/MSS 실사 및 방화벽 패킷 검사 룰셋 갱신** | 패킷 손실률 0% 달성 및 기존 네트워크 장비와의 완벽한 공존 보장 |

#### 한줄 요약
- 암호 민첩성으로 코드 수정을 방지하고, 폴백 차단으로 다운그레이드를 막으며, MTU 검증으로 패킷 드롭을 예방한다.

## Ⅶ. 결론

- 양자 컴퓨팅에 의한 암호학적 위기(Y2Q)에 선제 대응하기 위해 **PQC 마이그레이션 및 하이브리드 전환 아키텍처**는 전 세계 정부 및 엔터프라이즈의 표준 가이드라인으로 확립되었으며, 실무 추진 시 **CBOM 기반의 자산 가시화**, **X25519+ML-KEM 하이브리드 키 교환의 선제 적용**, **엄격한 레거시 폴백 차단 및 암호 민첩성 설계**를 결합하여 단절 없는 무결점 차세대 암호 전환을 완성

#### 한줄 요약
- CBOM 자산 식별과 하이브리드 KEM 결합 및 암호 민첩성 설계를 통해 안전하고 유연한 PQC 마이그레이션을 실현한다.
