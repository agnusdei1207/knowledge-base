## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **양자내성암호(Post-Quantum Cryptography, PQC) 전환**: 양자 공격에 취약한 공개키 암호를 양자내성 키 설정•서명 방식으로 단계적으로 교체하는 작업이다.
- **지금 수집•나중 해독(Harvest Now, Decrypt Later, HNDL)**: 현재 암호문을 수집•보관한 뒤 미래의 양자컴퓨터로 해독하려는 위협이다.

</details>

- 정의/개념: 양자 취약 암호를 KEM과 서명으로 바꾸는 **PQC 전환** 활동이다.
- 배경/필요성: 숨은 암호 의존성은 **HNDL** 위험에 따른 전환 순서 결정을 어렵게 한다.

#### 한줄 요약

- 새 암호를 설치하기 전에 낡은 자물쇠가 어느 서비스•인증서•장비에 숨어 있고 무엇이 그 자물쇠에 의존하는지 찾아야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **하이브리드 방식(Hybrid Mode)**: 기존 공개키 암호와 양자내성암호의 결과를 결합하여 전환기 호환성과 보안을 함께 확보하는 방식이다.
- **암호 민첩성(Crypto Agility)**: 알고리즘과 매개변수를 코드에 고정하지 않고 정책과 공급자 경계에서 교체할 수 있는 설계 특성이다.

</details>

- 데이터 보존기간과 위협 시점을 기반으로 전환 우선순위를 정한다.
- **하이브리드 방식**으로 고전•PQC 비밀을 결합해 단일 알고리즘 실패를 완화한다.
- 정책•공급자 경계의 **암호 민첩성**으로 알고리즘 교체가 핵심이다.
- 자동 약화를 금지하여 PQC 협상 실패를 가시화한다.

#### 한줄 요약

- 두 자물쇠를 달아도 연결 장치가 한쪽만 열리면 통과시키도록 만들면 약한 자물쇠 하나가 전체 보안을 결정한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **암호 자재명세서(Cryptographic Bill of Materials, CBOM)**: 시스템이 사용하는 알고리즘•키•인증서•암호 라이브러리와 의존 관계를 기록한 목록이다.
- **결합기(Combiner)**: 기존 방식과 PQC 방식이 생성한 비밀을 하나의 세션키 원재료로 결합하는 함수이다.

</details>

```text
PQC 전환 구조
├─ 서비스•민첩성 결합기
├─ 고전 암호 공급자
├─ PQC 공급자
├─ CBOM•위험 우선순위
└─ 검증•전환 정책
```

가지의 의미: 결합•호환•양자 대응•자산•정책 책임을 나눈 구조다.

| 구성요소 | 책임 |
|:---|:---|
| 서비스•민첩성 결합기 | **암호 민첩성**과 **결합기**로 알고리즘 교체•비밀 결합 통제 |
| 고전 암호 공급자 | 전환기 기존 호환 기능 제공 |
| PQC 공급자 | **PQC 전환**용 양자내성 KEM•서명 제공 |
| CBOM•위험 우선순위 | **CBOM**으로 암호 위치•의존성•보존기간 연결 |
| 검증•전환 정책 | 호환성•실패•고전 암호 폐기 판정 |


#### 한줄 요약

- 서비스 이름만 적으면 교체가 실패하므로, 그 서비스가 쓰는 인증서•라이브러리•장비와 다른 시스템의 의존성까지 CBOM에 연결한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **키 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)**: 공유 비밀과 캡슐화 암호문을 생성하고 개인키로 동일한 비밀을 복구하는 방식이다.
- **시범 배포**: 제한된 대표 서비스에서 PQC의 크기•호환성•실패 처리를 먼저 검증하는 단계이다.
- **전환 우선순위 산정**: 암호 자산의 위치•기밀 수명•양자 위협 시점을 평가하여 적용 순서를 정하는 단계이다.
- **PQC KEM 시범 배포**: 대표 서비스에 양자내성 키 설정 공급자를 제한적으로 적용하는 단계이다.
- **크기•호환성•실패 검증**: 새 키•암호문의 크기와 장비•프로토콜 호환성 및 실패 동작을 확인하는 단계이다.
- **운영 전환**: 검증을 통과한 범위에 새 알고리즘을 확대 적용하는 단계이다.
- **고전 협상 차단**: 전환 완료 범위에서 기존 취약 알고리즘으로 자동 약화되는 협상을 거부하는 단계이다.

</details>

```text
CBOM•보존기간 입력
        │
        ▼
1. 전환 우선순위 산정
        │
        └── 결합•실패 규칙 확정
                    │
                    ▼
2. PQC KEM 시범 배포
        │
        ▼
3. 크기•호환성•실패 검증
        ├─ 실패: 설계•장비 보완
        └─ 통과
             │
             ▼
     4. 운영 전환
             │
             ▼
     5. 고전 협상 차단
             │
             └── 전환 완료 증적 반환
```

### 동작 원리

1. **전환 우선순위 산정**: 취약 암호 위치•기밀 수명을 평가한다.
2. **PQC KEM 시범 배포**: **KEM**을 **시범 배포**하여 새 키 설정 공급자를 적용한다.
3. **크기•호환성•실패 검증**: 장비•프로토콜 한계를 확인한다.
4. **운영 전환**: 검증 통과 범위에 새 알고리즘을 확대한다.
5. **고전 협상 차단**: 전환 완료 범위의 자동 약화를 금지한다.


#### 한줄 요약

- 새 자물쇠 사용률이 높아도 옛 열쇠로 들어오는 문이 하나 남으면 전환이 끝난 것이 아니므로, 마지막에는 실제 연결에서 옛 방식이 거부되는지 확인한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **고전 방식 유지**: 기존 공개키 알고리즘만 사용하는 단기 예외 방식이다.
- **PQC 단독 전환**: 모든 구간이 PQC를 지원한 뒤 고전 방식 선택지를 제거하는 방식이다.

</details>

| PQC 전환 방식 | 하이브리드 전환 | 고전 방식 유지 | PQC 단독 전환 |
|:---|:---|:---|:---|
| 적용 기준 | 지원 장비가 혼재한 전환기 | 불가피한 단기 예외 | 전 구간 PQC 지원 완료 |
| 핵심 특징 | **하이브리드 방식**으로 고전•PQC 비밀 결합 | **고전 방식 유지**로 기존 알고리즘만 사용 | **PQC 단독 전환**으로 PQC KEM•서명만 사용 |
| 한계 | 결합•실패 처리 복잡성 | **HNDL** 노출 지속 | 미지원 장비와 연결 단절 |

> 요약: 지원 범위에 따라 하이브리드에서 단독을 전환한다.

#### 한줄 요약

- 모든 장비가 새 암호를 이해하기 전에는 두 결과를 결합하고, 전체 경로가 PQC를 지원하면 고전 방식 선택지를 제거한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **미국 국립표준기술연구소(National Institute of Standards and Technology, NIST)**: 미국의 기술 표준과 지침을 개발하는 기관이다.
- **사이버보안 백서(Cybersecurity White Paper, CSWP) 15**: PQC 도입 과제와 암호 자산 식별•전환 계획을 제시하는 지침이다.
- **특별 간행물(Special Publication, SP) 800-227**: KEM의 안전한 구현•사용과 공유 비밀 설정을 권고하는 지침이다.
- **다운그레이드 공격(Downgrade Attack)**: 협상 정보를 조작하여 지원 가능한 방식보다 약한 암호를 선택하게 하는 공격이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 암호 자산•우선순위 누락 | **NIST** **CSWP 15** 기반 조사 | HNDL 위험순 전환 |
| KEM 결합•실패 처리 오류 | **NIST** **SP 800-227** 검증 | 비밀 결합 오류 억제 |
| 자동 약화 협상 | **다운그레이드 공격** 탐지•연결 증적 감사 | 약한 방식 선택 차단 |

#### 한줄 요약

- 오늘 암호문이 수년 뒤에도 가치가 있는 서비스부터 KEM을 바꿔, 데이터 보존기간이 예상 전환 완료 시점보다 길면 HNDL 위험을 먼저 줄인다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **전환 완료 기준**: PQC 적용률뿐 아니라 실제 연결에서 고전 방식이 더 이상 선택되지 않는 상태까지 포함하는 종료 조건이다.

</details>

- **전환 완료 기준**에 따라 지원 혼재 구간은 **하이브리드 방식**, 전 구간 지원 후에는 **PQC 단독 전환**을 적용한다.

#### 한줄 요약

- 새 알고리즘을 켜는 데서 끝나지 않고, 데이터 수명과 장비 지원을 확인한 뒤 옛 알고리즘이 실제로 선택되지 않게 해야 전환이 끝난다.
