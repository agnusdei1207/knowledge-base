## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 구성 관리 (SCM)**: 서버나 인프라 설정을 처음에 합의한 "가장 안전한 상태(기준선)"로 팩트로 꽉 묶어두고 유지하는 통제 활동이다.
- **구성 편차 (Configuration Drift)**: 실무자가 편하게 일하려고 방화벽을 임의로 열거나, 긴급 장애 조치하다가 원래 안전했던 설정(기준선)에서 팩트로 어긋나버린(Drift) 틈새 상태다.

</details>

- 정의: IT 자산의 시스템, OS, 애플리케이션 설정을 사전 승인된 안전한 보안 기준선(Baseline)으로 팩트 통제하고 유지하는 체계다.
- 배경: 멀쩡했던 서버도 운영자가 귀찮다고 임의로 설정을 뜯어고치면(구성 편차), 그 열린 구멍으로 해커가 타고 들어와 치명적 취약점이 팩트로 터지기 때문이다.

#### 한줄 요약

- 처음에 안전하게 세팅해 둔 룰(기준선)을 몰래 바꾸지 못하게 감시하고, 누가 바꾸면 팩트로 원래대로 돌려놓는 관리 체계다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **보안 기준선 (Security Baseline)**: "이 서버는 비밀번호 최소 10자리, 안 쓰는 포트는 전부 닫기"처럼 무조건 지켜야 할 최소한의 팩트 하드닝(Hardening) 가이드라인이다.
- **보상 통제 (Compensating Controls)**: 특정 레거시 솔루션 때문에 10자리 비번을 못 쓰면, 대신 OTP라도 달아놓는 식의 팩트 땜빵 방어 통제다.

</details>

- **팩트 보안 기준선 표준 정의**: 자산 종류와 버전, 환경별로 최소한 지켜야 할 보안 설정(Baseline)을 팩트로 쾅 박아둔다.
- **팩트 이중 관찰 체계**: 소스 코드(IaC)를 배포하기 전에 한 번 검사하고, 서버가 굴러갈 때도 누가 몰래 설정을 바꾸지 않는지 런타임 편차(Drift)를 상시 팩트 감시한다.
- **팩트 자동 원복 및 예외 통제**: 무단 변경이 걸리면 즉시 10분 전 원래 상태로 팩트 강제 원복(Auto-remediation)하고, 진짜 불가피한 예외는 보상 통제를 달아 기한부로만 열어준다.

#### 한줄 요약

- 기준선을 딱 정해놓고, 배포 전에도 검사하고 배포 후에도 계속 감시해서, 룰 어기면 팩트로 자동 복구(원복) 시켜버린다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 검사 (Policy Check)**: 인프라를 찍어내기 전(배포 전)에 "이거 보안 기준 지켰어?" 하고 코드를 팩트로 깐깐하게 검사하는 문지기다.
- **편차 탐지 (Drift Detection)**: 서버가 굴러가고 있을 때 스캐너가 팩트로 상시 찔러봐서 "어? 며칠 전에 방화벽 설정 누가 맘대로 바꿨네?" 하고 잡아내는 레이더다.

</details>

```text
[ 보안 구성 관리(SCM) 팩트 통제 아키텍처 ]

[ 1. 자산 정보 및 기준선 매핑 ] ── ("웹 서버는 웹 기준선, DB는 DB 기준선 팩트로 짝지음")
      │
      ▼
[ 2. 배포 전 정책 검사 (Pre-flight) ] ── ("코드 커밋할 때 보안 룰 안 맞으면 팩트 배포 원천 차단해!")
      │
      ▼
[ 3. 승인 구성 팩트 배포 ] ── ("검사 통과한 100% 안전한 설정만 운영망에 팩트로 밀어 넣음")
      │
      ▼
[ 4. 실행 중 편차 탐지 (Drift) ] ── ("운영 중에 누가 몰래 포트 열었는지 상시 팩트 감시(스캔)함")
      │
      ▼
[ 5. 자동 복구 및 예외 관리 ] ── ("무단으로 포트 열린 거 발견! 당장 안전한 상태로 팩트 강제 원복!")
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **자산 및 기준선 매핑** | 장비 종류마다 지켜야 할 **가이드라인(Baseline)을 팩트로 연결함** | Mapping |
| **배포 전 정책 검사** | 구멍 난 설정 코드는 **운영망에 배포조차 못 하게 사전에 팩트 컷함** | Pre-check |
| **승인 구성 팩트 배포** | 안전이 입증된 설정만 **실제 운영망에 팩트로 밀어 넣음** | Deploy |
| **런타임 편차 탐지** | 몰래 설정 바꿔서(Drift) **안전 기준선을 이탈한 놈을 팩트로 적발함** | Detection |
| **자동 복구 및 예외** | 적발되면 즉시 원상 복구하고, **불가피할 때만 예외 처리 기한을 둠** | Remediate |

#### 한줄 요약

- 설계도(코드)부터 팩트 검사하고, 돌아가는 동안에도 몰래 바꾸면 레이더로 잡아내서 멱살 잡고 팩트 복구한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ 보안 구성 편차 탐지 및 팩트 자동 복구 흐름 ]

┌──────────────────────────────┐
│ 1. [환경별 보안 기준선 팩트 매핑]
│ ("우리 회사 리눅스 서버는 리눅스 CIS 벤치마크 팩트 적용해!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [배포 전 보안 정책 팩트 검사 (IaC 검사)]
│ ("테라폼 코드에 비밀번호 하드코딩 됐네? 배포 팩트 중단!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [승인 구성 운영망 팩트 배포]
│ ("코드 클린! 운영망 서버에 팩트로 안전하게 세팅 완료!")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 4. [런타임 구성 편차(Drift) 및 영향 팩트 분석]
    │ ("어? 일주일 뒤에 보니까 개발자가 편하게 일하려고 방화벽 몰래 팩트로 내렸네?")
    └──────────────┬───────────────┘
                   ▼
    ┌──────────────────────────────┐
    │ 5. [자동 팩트 원복(Remediation) 및 기한부 예외 처리]
    │ ("무단 변경 적발! 당장 원래 방화벽 설정으로 팩트 롤백(원상 복구)시켜!")
    └──────────────────────────────┘
```

### 동작 원리

1. 환경별 보안 기준선 매핑: 자산 유형 및 서비스 환경에 표준 하드닝(Hardening) 기준선을 결합함.
2. 배포 전 정책 검사: CI/CD 파이프라인에서 인프라 배포(IaC) 코드의 정책 이행을 정적으로 팩트 검증함.
3. 승인 구성 배포: 사전 검증을 통과한 규격 충족 안전 설정만 프로덕션 환경에 팩트 배포함.
4. 구성 편차/영향 분석: 런타임 실제 설정과 목표 상태 간의 드리프트(Drift)를 상시 스캔 및 팩트 식별함.
5. 자동 복구 및 예외 처리: 저위험 편차는 자동 원상 복구하고, 비즈니스상 불가피한 경우 심의를 거쳐 팩트 예외 처리함.

#### 한줄 요약

- 배포 전에 코드 검사 팩트로 조지고 $\to$ 배포 후에도 몰래 바꾸면(편차) $\to$ 가차 없이 팩트 강제 원복(롤백)한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정기 수동 점검**: 보안팀이 한 달에 한 번씩 서버에 직접 들어가서 설정이 맞는지 수동으로 팩트 체크하는 옛날 방식이다.
- **실행 중 편차 탐지 (Runtime Drift Detection)**: 보안 에이전트(Agent)가 24시간 내내 운영 장비 설정을 감시해서 몰래 바꾼 걸 실시간 팩트 적발하는 최신 방식이다.

</details>

| 구성 점검 유형 | **정기 수동 팩트 점검** | **배포 전 정책 검사 (IaC)** | **실행 중 편차 탐지 (Drift)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **한 달에 한 번 수위 아저씨가 순찰 돌기** | **건물 짓기 전에 설계도면 팩트 검사하기** | **건물 곳곳에 24시간 동작 감시 CCTV 달기** |
| 핵심 탐지 방식 | 점검 스크립트나 담당자가 장비에 직접 들어가서 **설정값 일일이 수동 팩트 확인** | CI/CD 파이프라인에서 인프라 구성 코드(IaC)를 **사전에 정적으로 팩트 스캔함** | 에이전트가 운영 장비의 실시간 상태를 모니터링하여 **기준 이탈을 팩트 적발함** |
| 장점 및 특징 | 자동화가 힘든 레거시 장비의 **복잡한 구성을 사람이 유연하게 팩트 판단함** | 구멍 난 인프라가 운영망에 올라가기 전에 **원천적으로 팩트 차단함 (Shift-Left)** | 누가 한밤중에 몰래 설정을 바꿔도 **수분 내로 팩트 적발 및 자동 원복 가능함** |
| 한계 및 문제점 | 한 달 사이(점검 주기)에 설정을 몰래 바꿨다가 원복하면 **팩트로 절대 못 잡음** | 코드로 인프라를 찍어내지(IaC) 않는 **옛날 수동 환경에선 적용 팩트 불가함** | 예외 로직 안 짜놓고 무지성 자동 원복(Auto-remediation) 걸면 **메인 서비스 팩트로 죽음** |

#### 한줄 요약

- 도면 검사(배포 전)로 미연에 방지하고, CCTV(런타임 탐지)로 몰래 바꾸는 놈을 팩트 적발해라.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **CIS Benchmarks**: 전 세계 보안 전문가들이 합의한 "리눅스는 이렇게, AWS는 무조건 이렇게 설정해라" 하는 글로벌 팩트 하드닝 바이블이다.
- **NIST SP 800-128**: "보안 구성 관리는 이렇게 절차 지켜서 통제해라" 하는 미국 정부의 팩트 가이드라인이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 기준선 빡세게 걸었더니 **멀쩡히 돌던 구형 사내 시스템이 팩트로 다 뻗음** | 각 서버의 업무 특성(레거시)을 무시하고, 너무 타이트한 획일화된 룰만 무지성 팩트 강제함 | **CIS Benchmarks**를 그대로 베끼지 않고, 각 회사 환경에 맞게 **기준선 팩트 테일러링(선별 조정)** | 과도한 하드닝(Hardening)으로 인한 서비스 가용성 파괴 방지 및 팩트 실무 수용성 확보 |
| 몰래 변경한 거 걸렸다고 **무지성 자동 원복 쳤다가 메인 DB 통신이 팩트로 끊김** | 긴급 장애 조치로 바꾼 상황을 무시하고, 예외 로직 1도 없이 자동 복구를 팩트 강행함 | 무중단 서비스는 자동 원복 전 **장애 영향도 팩트 분석** 및 승인 절차(Human-in-the-loop) 연계 | 편차 자동 복구 로직의 폭주로 인한 대규모 2차 서비스 장애 팩트 원천 방어 |
| 한 달만 포트 열어달라고 **예외 승인받더니 1년째 팩트 방치 중임** | "나중에 닫을게요" 해놓고 보안팀이 추적 관리를 팩트로 안 해서 기술 부채 구멍이 쌓임 | 구성 예외 건에 대해 **기한부 예외 만료(Expiration) 관리** 및 기한 경과 시 팩트 강제 자동 원복 | 잊혀진 예외 설정(방치된 구멍) 누적으로 인한 침해 위협 팩트 원천 제거 |

#### 한줄 요약

- 회사 사정 맞춰서 기준선 조정하고, 예외 승인 내준 건 날짜 지나면 얄짤없이 팩트로 닫아버려라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **예외 만료 관리 (Exception Expiration Management)**: 사유가 명확해서 한 달만 방화벽 열어주기로 한 '구성 예외 건'에 대해, 날짜 지나면 귀신같이 팩트로 문 닫고 원복시키는 관리 절차다.

</details>

- 보안 구성 관리는 단순 일회성 셋팅이 아니므로, **CIS Benchmarks** 기반의 안전한 기준선을 수립하고, **배포 전 검사**와 **런타임 편차(Drift)** 탐지를 연계하되, 고위험 무단 변경은 즉시 자동 팩트 원복하고 불가피한 예외는 철저한 **예외 만료 관리**로 통제하는 팩트 실무 기조를 확립함

#### 한줄 요약

- 몰래 바꾸면(Drift) 가차 없이 원상 복구하고, 승인받은 예외도 기한 끝나면 팩트로 칼같이 원복해라.
