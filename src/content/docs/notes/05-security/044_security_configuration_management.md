## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 구성 관리(Security Configuration Management, SCM)**: IT 자산의 OS, 시스템 소프트웨어, 애플리케이션 및 인프라 설정을 사전 승인된 안전한 보안 기준선(Baseline)으로 통제•유지하는 보안 관제 활동.
- **구성 편차(Configuration Drift)**: 수동 작업, 긴급 장애 조치, 오설정 등으로 인해 실운영 자산의 실제 설정이 승인된 기본 보안 기준선에서 벗어난 상태.

</details>

- 정의/개념: 실제 설정을 **보안 기준선**에 맞추는 구성 통제
- 배경/필요성: 분산 환경의 임의 변경은 **구성 편차•취약점** 유발

#### 한줄 요약

- 초기 배포 시 승인된 안전한 보안 기준선과 실운영 중 발생하는 구성 편차를 지속 점검해 자동 복구함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **보안 기준선(Security Baseline)**: 자산 종류, 환경, 버전별로 최소한으로 준수해야 할 필수 보안 설정 가이드라인.
- **보상 통제(Compensating Controls)**: 비즈니스 영향이나 유효성 한계로 보안 기준선을 직접 적용할 수 없을 때 동등 수준의 위험 감축 효과를 제공하는 대체 통제.

</details>

- 자산 유형, 소프트웨어 버전 및 운용 환경별 **보안 기준선** 표준 정의.
- CI/CD 파이프라인 배포 전 정책 검증과 런타임 수시 편차 탐지의 이중 관찰 체계.
- 편차 발견 시 비즈니스 위험도에 따른 자동 원상 복구(Auto-remediation) 및 기한부 **보상 통제** 처리.

#### 한줄 요약

- 보안 기준선을 정립하고 예외 승인 시 사유, 기간, 대체 보상 통제를 명시하여 임의 구성을 차단함.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 검사(Policy Check / Pre-flight Assessment)**: 소스 코드 배포 또는 IaC 커밋 이전 단계에서 보안 지침 준수 여부를 자동 판정하는 사전 검사.
- **편차 탐지(Drift Detection)**: 런타임 상태를 수시 스캐닝하여 최초 승인 상태와의 구성 차이를 식별 추적하는 탐지.

</details>

```text
보안 구성 관리
├─ 자산 정보: 자산별 기준 연결
├─ 버전 기준: 승인 설정•변경 이력 관리
├─ 정책 검사: 배포 전 위반 판정
├─ 편차 탐지: 목표•실제 상태 차이 식별
└─ 예외 복구: 사유•만료•복구 영향 통제
```

| 구성요소 | 책임 |
|:---|:---|
| 자산 정보 | 자산 유형, IP, 소프트웨어 버전별 보안 하드닝 기준 매핑 |
| 버전 기준 | **보안 기준선** 버전 통제 및 변경 이력 무결성 관리 |
| 정책 검사 | CI/CD 연동 사전 **정책 검사** 기반 규정 위반 배포 차단 |
| 편차 탐지 | 런타임 스캔 기반 목표 상태 대비 실제 **편차 탐지** |
| 예외 복구 | 자동 복구 집행 및 기한부 예외의 **보상 통제** 만료 관리 |

#### 한줄 요약

- 사전 정책 검사와 런타임 편차 탐지를 연계하여 승인 기준선 이탈을 차단함.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **코드형 인프라(Infrastructure as Code, IaC)**: 서버, 네트워크 등 인프라 구성을 테라폼, 앤서블 등의 코드 형태로 정의 및 관리하는 기술.
- **지속적 통합•제공(Continuous Integration/Continuous Delivery, CI/CD)**: 개발부터 테스트, 배포까지의 과정을 자동화 파이프라인으로 구성하는 DevOps 방법론.
- **롤백(Rollback)**: 형상 변경 후 예기치 않은 오류 발생 시 이전의 안전한 정상 설정 버전으로 되돌리는 원상복구 절차.
- **환경별 보안 기준선 매핑(Baseline Mapping)**: 대상 환경별로 표준 승인 하드닝 템플릿을 연결하는 단계.
- **배포 전 정책 검사(Static Policy Enforcement)**: IaC 및 형상 변경 코드의 정책 이행을 정적 검증하는 단계.
- **승인 구성 배포(Deployment)**: 사전 검증을 통과한 인프라 구성 코드를 배포 집행하는 단계.
- **구성 편차•영향 분석(Drift & Impact Analysis)**: 런타임 실제 설정과 저장소 기준선과의 차이를 분석하는 단계.
- **자동 복구•예외 처리(Auto-remediation & Exception Handling)**: 승인된 스크립트로 오설정을 원상 복구하거나 기한부 예외를 적용하는 단계.

</details>

```text
자산•환경 정보
       │
       ▼
1. 환경별 보안 기준선 매핑
       │
       ▼
2. 배포 전 정책 검사
       │
       ├─ 위반 ── 변경 수정•재검사
       │
       └─ 통과 ── 3. 승인 구성 배포
                         │
                         ▼
                 실행 중 지속 점검
                         │
                         ▼
              4. 구성 편차•영향 분석
                         │
             ┌───────────┴───────────┐
             │                       │
        복구 안전                  복구 위험
             │                       │
             └─ 5. 자동 복구•예외 처리
```

### 동작 원리

1. **환경별 보안 기준선 매핑**: 자산 유형 및 서비스 환경에 표준 기준선 결합.
2. **배포 전 정책 검사**: CI/CD 파이프라인 상에서 IaC 변경 코드 정적 산출 검사.
3. **승인 구성 배포**: 규격 충족 설정만 프로덕션 환경 배포 집행.
4. **구성 편차•영향 분석**: 런타임 드리프트 식별 및 복구 시 장애 파급력 측정.
5. **자동 복구•예외 처리**: 안전 편차는 자동 원상 복구, 고위험 편차는 예외 승인 및 보상 통제 적용.

#### 한줄 요약

- 보안 기준선 매핑, 배포 전 검사, 승인 배포, 편차 영향 분석 및 자동 복구/예외 처리를 연결함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정기 수동 점검(Manual Compliance Audit)**: 주기적 또는 수작업으로 대상 장비에 직접 접속하여 보안 구성을 일일이 점검하는 방식.
- **실행 중 편차 탐지(Continuous Runtime Drift Detection)**: Agent 또는 API 기반으로 운영 환경 설정을 지속 감시하여 실시간 이탈을 탐지하는 방식.

</details>

| 구성 점검 유형 | 정기 수동 점검 | 배포 전 정책 검사 | 실행 중 편차 탐지 |
|:---|:---|:---|:---|
| 적용 기준 | 자동 수집 곤란•현장 판단 | **IaC**•**CI/CD** 변경 | 수동•긴급 변경 탐지 |
| 핵심 특징 | **정기 수동 점검** | **배포 전 정책 검사** | **실행 중 편차 탐지** |
| 한계 | 점검 사이 편차 누락 | 배포 외 변경 누락 | 오탐•자동 복구 장애 |

#### 한줄 요약

- 사전 배포 검사를 통해 보안 오설정을 예방하고, 런타임 편차 탐지로 임의 구성을 상시 적발함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **미국 국립표준기술연구소 SP 800-128(NIST SP 800-128)**: 시스템 보안 구성 관리의 절차와 기준선 통제를 정의한 가이드라인.
- **CIS 벤치마크(CIS Benchmarks)**: 전 세계 보안 전문가들이 합의 수립한 OS, DB, 클라우드별 구체적 설정 가이드.
- **인터넷 보안 센터(Center for Internet Security, CIS)**: IT 시스템 보안 하드닝 벤치마크를 개발 배포하는 국제 비영리 기관.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 체계적 거버넌스 미비 | **NIST SP 800-128** 적용 | 전사 구성 통제 책임 정형화 |
| 획일적 지침에 따른 서비스 장애 | **CIS Benchmarks** 환경별 선별 조정 | 하드닝 보안성과 호환성 균형 |
| 자동 복구 오작동 파급 | 예외 통제, 장애 영향 분석 및 **롤백** | 서비스 가용성과 복구 안전성 확보 |

#### 한줄 요약

- S3 버킷 설정이 외부 공개로 무단 변경된 편차 발생 시, 선언된 IaC 정책 코드로 자동 원복 조치함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **예외 만료 관리(Exception Expiration Management)**: 사유가 명확한 구성 예외 건에 대해 대체 보상 통제 및 시한을 두고 주기적으로 잔존 여부를 평가하여 자동 정상화하는 절차.

</details>

- **예외 만료 관리**를 적용하여 저위험 편차는 자동 원복 처리하고 업무 파급도가 높은 오설정은 예외 심의 후 관제 조치.

#### 한줄 요약

- 저위험 편차는 **자동 복구**, 고영향 편차는 **예외 심의**
