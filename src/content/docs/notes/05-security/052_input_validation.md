## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **입력값 검증(Input Validation)**: 외부 입력이 허용된 형식•길이•범위에 맞는지 검증하는 통제 기법.
- **파라미터 바인딩(Parameter Binding)**: 실행 구문과 외부 입력값을 분리해 데이터가 명령으로 해석되지 않게 방지하는 메커니즘.

</details>

- 정의/개념: 외부 입력의 업무 계약 맞춤 제한 및 **파라미터 바인딩**을 통한 실행 구문과 값 분리.
- 배경/필요성: 차단 목록 방식의 인코딩 변형 및 우회 공격 한계 극복 필요.

#### 한줄 요약

- 입력값 검증은 외부 값을 업무 계약에 맞는 데이터로 제한해 구문•자원•권한 공격의 출발점을 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **허용 목록(Allowlist)**: 사전 승인된 값이나 형식만 통과시키는 입력 제한 방식.
- **정규화(Normalization)**: 다양한 인코딩과 중복 표현을 하나의 표준 표현으로 통일하는 처리 절차.
- **동적 식별자(Dynamic Identifier)**: 테이블•열 이름처럼 파라미터 바인딩이 불가능해 허용 목록 매핑이 필요한 구문 요소.

</details>

- **정규화** 수행 후 서버의 **허용 목록** 기반 형식•길이•범위 판정.
- **파라미터 바인딩**을 통한 외부 입력의 순수 데이터 처리.
- **동적 식별자**의 사전 승인된 테이블•열 이름 매핑 적용.

#### 한줄 요약

- 허용 목록과 길이•형식•범위 검사는 입력을 제한하지만 출력 인코딩이나 매개변수화 질의를 대신하지 않는다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **파서(Parser)**: 입력 문자열을 정해진 문법 구문에 따라 해석하는 처리 구성요소.
- **안전 실행 응용 프로그래밍 인터페이스(Secure Execution Application Programming Interface, Secure Execution API)**: 고정 구문과 매개변수 값을 분리하여 실행점에 전달하는 인터페이스.

</details>

```text
입력 보안 통제
├─ 입력 계약: 형식•길이•범위 정의
├─ 단일 파서: 인코딩•콘텐츠 형식 통일
├─ 서버 검증기: 허용 목록•업무 규칙 판정
├─ 안전 실행 API: 구문•외부 값 분리
└─ 오류•감사: 일반 오류•차단 기록
```

| 구성요소 | 책임 |
|:---|:---|
| 입력 계약 | 형식•길이•범위 규칙 정의 |
| 단일 파서 | **파서**로 인코딩•콘텐츠 형식 통일 |
| 서버 검증기 | **허용 목록**•업무 규칙 판정 |
| 안전 실행 API | **안전 실행 응용 프로그래밍 인터페이스**로 구문•외부 값 분리 전달 |
| 오류•감사 | 일반 오류 응답•차단 기록 |

#### 한줄 요약

- 계약 스키마가 구조와 크기를 제한하고 정규화•업무 검증을 통과한 값만 안전한 처리기에 전달한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **입력 계약(Input Contract)**: 형식•길이•범위•배열 개수•중첩 깊이와 전체 크기를 명시적으로 제한하는 명세 지침.
- **데이터베이스(Database, DB)**: 구조화된 데이터를 저장•관리하고 질의를 처리하는 데이터 저장소.
- **구조화 질의 언어(Structured Query Language, SQL) 구조**: 데이터베이스가 실행할 질의 명령의 고정 템플릿 구문.
- **정규화 입력(Normalized Input)**: 외부 입력의 다양한 인코딩과 변형 표현을 단일 표준 형식으로 변환하는 단계.
- **허용된 업무 값 검증(Business Value Validation)**: 입력 계약과 업무 규칙에 따라 형식•범위•권한•상태의 적합성을 확인하는 과정.
- **고정 SQL 구조 생성(Prepared Statement Generation)**: 외부 값과 분리된 데이터베이스 질의 명령 형식을 사전에 정의하는 단계.
- **입력값 파라미터 바인딩(Input Parameter Binding)**: 검증된 외부 입력을 고정 질의 구문의 매개변수로 안전하게 결합하는 절차.
- **최소 권한 질의 실행(Least Privilege Query Execution)**: 허용된 스키마와 연산 범위 내에서만 데이터베이스 질의를 처리하는 단계.

</details>

```text
외부 입력 문서
      |
      v
1. 정규화 입력
      |
      v
2. 허용된 업무 값 검증
      |
      v
3. 고정 SQL 구조 생성
      |
      v
4. 입력값 파라미터 바인딩
      |
      v
5. 최소 권한 질의 실행
      |
      v
제한된 질의 결과
```

### 동작 원리

1. **정규화 입력**: 인코딩 및 중복 표현을 단일 표준 형식으로 변환하는 정규화 입력 단계.
2. **허용된 업무 값 검증**: 형식•길이•범위•권한•상태 판정을 위한 허용된 업무 값 검증 수행.
3. **고정 SQL 구조 생성**: 외부 값과 분리된 질의 명령 형식을 고정하는 고정 SQL 구조 생성.
4. **입력값 파라미터 바인딩**: 외부 입력을 명령이 아닌 값으로 결합하는 입력값 파라미터 바인딩 수행.
5. **최소 권한 질의 실행**: 허용된 스키마 및 연산 범위 내 최소 권한 질의 실행.


#### 한줄 요약

- 서버는 **입력 계약**을 확인한 뒤 **SQL 구조**와 값을 분리해 **DB**에 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **입력 처리 역할 분리(Input Processing Separation)**: 정규화, 입력 검증, 파라미터 바인딩의 역할을 명확히 구분하는 설계 원칙.

</details>

| 처리 단계 | 역할 | 주의점 |
|:---|:---|:---|
| **정규화** | 중복 표현을 단일 형식으로 통일 | 검증 전에 한 번만 수행하여 의미 변경 방지 |
| **입력값 검증** | 업무 허용 범위•형식 판정 | 출력 문맥별 인코딩을 별도로 적용 |
| **파라미터 바인딩** | 실행 구문과 값을 분리 | **동적 식별자**는 허용 목록으로 제한 |

#### 한줄 요약

- **입력 처리 역할 분리**에 따라 입력 검증은 값의 적합성, 정규화는 표현 통일, 바인딩은 구문 분리를 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **MITRE CWE-20(MITRE Common Weakness Enumeration 20)**: 입력의 유효성을 올바르게 검증하지 않는 보안 약점을 정의한 공통 약점 분류.
- **OWASP ASVS 5.0.0(OWASP Application Security Verification Standard 5.0.0)**: 입력 검증 및 인젝션 방지 요구사항을 제시하는 보안 표준 규격.
- **객체 관계 매핑(Object-Relational Mapping, ORM)**: 객체 지향 프로그래밍 언어의 객체와 관계형 데이터베이스 테이블을 자동으로 매핑하는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 계약 검증이 없으면 비정상 값이 실행점 도달 | **MITRE CWE-20** 기준으로 서버 검증 | 비정상 형식•범위 조기 차단 |
| 검증과 인코딩•바인딩을 혼동하면 주입 경로 잔존 | **OWASP ASVS 5.0.0** 적용 | 문맥별 통제 책임 구분 |
| **ORM** 원시 질의의 동적 식별자와 과대 입력으로 주입•자원 고갈 | **허용 목록**•크기•깊이 제한 적용 | 식별자 주입과 과부하 방지 |

#### 한줄 요약

- API 계약에 문자열 길이, 배열 개수, 중첩 깊이와 전체 본문 크기를 정하고 이를 넘는 요청은 처리 전에 거부한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **입력 통제 적용 기준(Input Control Standard)**: 값 검증, 파라미터 바인딩, 동적 식별자 매핑 및 자원 크기 제한을 규정한 통제 지침.

</details>

- **입력 통제 적용 기준**에 따라 값의 **허용 목록** 검증 및 **파라미터 바인딩**, 식별자의 코드 매핑, 입력 깊이•크기 제한 적용.

#### 한줄 요약

- 입력값 검증은 계약 제한과 문맥별 안전 처리, 자원 제한을 함께 적용해야 한다.
