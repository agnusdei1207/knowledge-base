## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **입력값 검증**: 외부 입력이 허용된 형식•길이•범위에 맞는지 확인하는 통제이다.
- **파라미터 바인딩**: 실행 구문과 외부 입력값을 분리해 데이터가 명령으로 해석되지 않게 하는 통제이다.

</details>

- 정의/개념: **입력값 검증**은 외부 값을 업무 계약에 맞게 제한하고 **파라미터 바인딩**은 값을 실행 구문과 분리한다.
- 배경/필요성: 차단 목록만으로는 다양한 인코딩과 변형 입력의 우회를 막기 어렵다.

#### 한줄 요약

- 입력값 검증은 외부 값을 업무 계약에 맞는 데이터로 제한해 구문•자원•권한 공격의 출발점을 줄인다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **허용 목록**: 승인한 값이나 형식만 통과시키는 입력 제한 방식이다.
- **정규화**: 같은 의미의 여러 표현을 하나의 표준 표현으로 바꾸는 처리이다.
- **동적 식별자**: SQL의 테이블•열 이름처럼 값 바인딩을 적용하기 어려워 승인된 이름으로 매핑해야 하는 구문 요소이다.

</details>

- **정규화**를 한 번 수행한 뒤 서버의 **허용 목록**으로 형식•길이•범위를 판정한다.
- **파라미터 바인딩**으로 외부 값을 명령이 아닌 데이터로 처리한다.
- **동적 식별자**의 승인된 테이블•열 이름 매핑이 핵심이다.

#### 한줄 요약

- 허용 목록과 길이•형식•범위 검사는 입력을 제한하지만 출력 인코딩이나 매개변수화 질의를 대신하지 않는다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **파서**: 입력 문자열을 정해진 문법 구조에 따라 해석하는 구성요소이다.
- **안전 실행 응용 프로그래밍 인터페이스(Application Programming Interface, API)**: 고정 구문과 값을 분리해 실행점에 전달하는 인터페이스이다.

</details>

```text
입력 보안 통제
├─ 입력 계약: 형식•길이•범위 정의
├─ 단일 파서: 인코딩•콘텐츠 형식 통일
├─ 서버 검증기: 허용 목록•업무 규칙 판정
├─ 안전 실행 API: 구문•외부 값 분리
└─ 오류•감사: 일반 오류•차단 기록
```

| 구성요소 | 책임 |
|:---|:---|
| 입력 계약 | 형식•길이•범위 규칙 정의 |
| 단일 파서 | **파서**로 인코딩•콘텐츠 형식 통일 |
| 서버 검증기 | **허용 목록**•업무 규칙 판정 |
| 안전 실행 API | **안전 실행 응용 프로그래밍 인터페이스**로 구문•외부 값 분리 전달 |
| 오류•감사 | 일반 오류 응답•차단 기록 |

#### 한줄 요약

- 계약 스키마가 구조와 크기를 제한하고 정규화•업무 검증을 통과한 값만 안전한 처리기에 전달한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **입력 계약**: 형식•길이•범위•배열 개수•중첩 깊이와 전체 크기를 제한하는 명세이다.
- **데이터베이스(Database, DB)**: 구조화된 데이터를 저장•질의하는 시스템이다.
- **구조화 질의 언어(Structured Query Language, SQL) 구조**: DB가 실행할 질의 명령의 고정 형식이다.
- **정규화 입력**: 외부 입력의 인코딩과 중복 표현을 표준 표현으로 바꾸는 단계이다.
- **허용된 업무 값 검증**: 입력 계약과 업무 규칙으로 형식•범위•권한•상태를 확인하는 단계이다.
- **고정 SQL 구조 생성**: 외부 값과 분리된 질의 명령 형식을 먼저 만드는 단계이다.
- **입력값 파라미터 바인딩**: 검증한 외부 입력을 고정 구문의 매개변수 값으로 전달하는 단계이다.
- **최소 권한 질의 실행**: 허용된 스키마와 연산 범위에서만 질의를 처리하는 단계이다.

</details>

```text
외부 입력 문서
      |
      v
1. 정규화 입력
      |
      v
2. 허용된 업무 값 검증
      |
      v
3. 고정 SQL 구조 생성
      |
      v
4. 입력값 파라미터 바인딩
      |
      v
5. 최소 권한 질의 실행
      |
      v
제한된 질의 결과
```

### 동작 원리

1. **정규화 입력**: 인코딩•중복 표현을 하나로 바꿔 정규화 입력을 만든다.
2. **허용된 업무 값 검증**: 형식•길이•범위•권한•상태에 대해 허용된 업무 값 검증을 수행한다.
3. **고정 SQL 구조 생성**: 외부 값과 분리된 명령 형식을 고정해 고정 SQL 구조를 생성한다.
4. **입력값 파라미터 바인딩**: 외부 입력을 명령이 아닌 값으로 결합해 입력값 파라미터 바인딩을 수행한다.
5. **최소 권한 질의 실행**: 허용된 스키마•연산 범위에서 최소 권한 질의를 실행한다.


#### 한줄 요약

- 서버는 **입력 계약**을 확인한 뒤 **SQL 구조**와 값을 분리해 **DB**에 전달한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **입력 처리 역할 분리**: 정규화는 표현 통일, 입력값 검증은 업무 적합성 판정, 파라미터 바인딩은 구문과 값 분리를 담당하는 원칙이다.

</details>

| 처리 단계 | 역할 | 주의점 |
|:---|:---|:---|
| **정규화** | 중복 표현을 단일 형식으로 통일 | 검증 전에 한 번만 수행하여 의미 변경 방지 |
| **입력값 검증** | 업무 허용 범위•형식 판정 | 출력 문맥별 인코딩을 별도로 적용 |
| **파라미터 바인딩** | 실행 구문과 값을 분리 | **동적 식별자**는 허용 목록으로 제한 |

#### 한줄 요약

- **입력 처리 역할 분리**에 따라 입력 검증은 값의 적합성, 정규화는 표현 통일, 바인딩은 구문 분리를 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **MITRE CWE-20**: 입력의 유효성을 잘못 검증하는 약점을 정의한 공통 약점 분류이다.
- **OWASP ASVS 5.0.0**: 입력•인젝션 방지 요구를 제시하는 애플리케이션 보안 검증 표준판이다.
- **객체 관계 매핑(Object-Relational Mapping, ORM)**: 객체와 데이터베이스 테이블을 연결하는 계층이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 계약 검증이 없으면 비정상 값이 실행점 도달 | **MITRE CWE-20** 기준으로 서버 검증 | 비정상 형식•범위 조기 차단 |
| 검증과 인코딩•바인딩을 혼동하면 주입 경로 잔존 | **OWASP ASVS 5.0.0** 적용 | 문맥별 통제 책임 구분 |
| **ORM** 원시 질의의 동적 식별자와 과대 입력으로 주입•자원 고갈 | **허용 목록**•크기•깊이 제한 적용 | 식별자 주입과 과부하 방지 |

#### 한줄 요약

- API 계약에 문자열 길이, 배열 개수, 중첩 깊이와 전체 본문 크기를 정하고 이를 넘는 요청은 처리 전에 거부한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **입력 통제 적용 기준**: 값은 허용 목록 검증과 바인딩, 동적 식별자는 코드 매핑, 전체 입력은 크기와 깊이 제한을 적용하는 기준이다.

</details>

- **입력 통제 적용 기준**에 따라 값은 **허용 목록** 검증과 **파라미터 바인딩**, 식별자는 코드 매핑, 입력은 깊이•크기를 제한한다.

#### 한줄 요약

- 입력값 검증은 계약 제한과 문맥별 안전 처리, 자원 제한을 함께 적용해야 한다.
