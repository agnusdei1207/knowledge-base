## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **입력값 검증(Input Validation)**: 외부 클라이언트로부터 유입되는 모든 데이터에 대해 데이터 타입, 길이, 정규식 패턴 및 허용 범위를 서버 측에서 검증하는 보안 통제.
- **파라미터 바인딩(Parameter Binding)**: DB SQL 문 및 외부 명령어 생성 시 실행 명령 구문과 사용자 입력 데이터를 물리적 파라미터로 격리 처리하는 기술.

</details>

- 정의/개념: 애플리케이션 외부 접점에서 유입되는 데이터를 허용목록(Allowlist) 스례로 정합성 검증하고, 백엔드 인터페이스 연결 시 **파라미터 바인딩(Parameter Binding)**을 적용하여 주입 공격을 원천 차단하는 보안 기술.
- 배경/필요성: 차단목록(Blacklist) 기반 필터링 우회 한계 극복 및 구문 해석기(Interpreter)로의 비신뢰 입력 인입 차단.

#### 한줄 요약

- 유입 데이터는 허용목록으로 검증하고, 쿼리/명령 처리 시 파라미터 바인딩으로 명령 구문과의 경계를 격리함.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **허용 목록(Allowlist / Positive Validation)**: 명시적으로 승인한 허용 문자열, 데이터 형식 및 값의 집합만 수용하고 나머지는 전면 거부하는 방어 기법.
- **정규화(Normalization / Canonicalization)**: 인코딩 및 우회 표현(URL Encoding, Unicode 등)을 단일 표준 이스케이프 형태로 변환 정제하는 사전 처리.
- **동적 식별자(Dynamic Identifier)**: 테이블명, 컬럼명, 정렬 순서 등 파라미터 바인딩이 불가능한 DB 객체명.

</details>

- **정규화(Normalization)** 사전 처리 후 서버 단의 **허용 목록(Allowlist)** 기반 형식, 길이 및 범위 정형 검증.
- PreparedStatement 등 **파라미터 바인딩(Parameter Binding)**을 통한 쿼리 실행 구문과 입력 데이터의 완전 격리.
- 매개변수 바인딩 불가능한 **동적 식별자(Dynamic Identifier)**의 경우 코드 사전 매핑 및 하드코딩 검증 통제.

#### 한줄 요약

- 정규화 후 허용목록 검증을 집행하며, 쿼리 생성 시 파라미터 바인딩을 적용하여 쿼리 변조를 막음.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **파서(Parser)**: HTTP body, JSON, XML 등 외부 데이터 포맷을 구문 분석하여 데이터 모델로 객체화하는 구성요소.
- **안전 실행 응용 프로그래밍 인터페이스(Secure Execution API)**: 사용자 입력을 쿼리 명령어가 아닌 파라미터 매개변수로만 처리하는 안전한 라이브러리.

</details>

```text
입력 보안 통제
├─ 입력 계약: 형식•길이•범위 정의
├─ 단일 파서: 인코딩•콘텐츠 형식 통일
├─ 서버 검증기: 허용 목록•업무 규칙 판정
├─ 안전 실행 API: 구문•외부 값 분리
└─ 오류•감사: 일반 오류•차단 기록
```

| 구성요소 | 책임 |
|:---|:---|
| 입력 계약 | API 스키마 상에 형식, 길이, 정규식 및 필수 파라미터 정의 |
| 단일 파서 | 단일 안전 **파서(Parser)**를 통해 URL/유니코드 인코딩 정규화 |
| 서버 검증기 | 클라이언트 검증 우회에 대응하는 **허용 목록** 기반 백엔드 검증 |
| 안전 실행 API | **안전 실행 API(Secure Execution API)**를 활용하여 쿼리 구문과 입력값 분리 |
| 오류•감사 | 취약한 시스템 에러 노출 방지 및 차단 이력 감사 로그 생성 |

#### 한줄 요약

- API 스키마 입력 계약, 단일 파서 정규화, 서버 허용목록 검증 및 안전 실행 API를 결합함.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **입력 계약(Input Contract)**: API 및 폼 명세서 상에 데이터 규칙을 정의하는 계약 스펙.
- **데이터베이스(Database, DB)**: 검증된 데이터가 파라미터 바인딩 쿼리를 통해 처리되는 저장소.
- **구조화 질의 언어(SQL) 구조**: PreparedStatement로 미리 사전 컴파일된 쿼리 골격체.
- **정규화 입력(Normalized Input)**: 우회 문자를 표준 디코딩하여 단일화하는 단계.
- **허용된 업무 값 검증(Allowlist Validation)**: 서버 측 허용목록 기반 정합성 판정 단계.
- **고정 SQL 구조 생성(Query Pre-compilation)**: DB 쿼리 구조체 컴파일 단계.
- **입력값 파라미터 바인딩(Parameter Binding)**: 입력 데이터를 pure 값으로 매핑하는 단계.
- **최소 권한 질의 실행(Least Privilege Execution)**: 최소 권한 계정으로 쿼리를 집행하는 단계.

</details>

```text
외부 입력 문서
      │
      ▼
1. 정규화 입력
      │
      ▼
2. 허용된 업무 값 검증
      │
      ▼
3. 고정 SQL 구조 생성
      │
      ▼
4. 입력값 파라미터 바인딩
      │
      ▼
5. 최소 권한 질의 실행
      │
      ▼
제한된 질의 결과
```

### 동작 원리

1. **정규화 입력**: 입력 인코딩 정제 및 표준 포맷 변환.
2. **허용된 업무 값 검증**: 백엔드 허용목록 및 정규식 기준 검증.
3. **고정 SQL 구조 생성**: DB 엔진 상에 SQL 실행계획 사전 컴파일.
4. **입력값 파라미터 바인딩**: 입력값을 바이트 파라미터 채널로 전달.
5. **최소 권한 질의 실행**: 애플리케이션 최소 권한 DB 계정으로 실행.

#### 한줄 요약

- 정규화, 허용목록 검증, 쿼리 구문 고정, 파라미터 바인딩 및 최소 권한 실행으로 이어짐.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **입력 처리 역할 분리(Input Defense Separation)**: 정규화(표현 단일화), 검증(허용 여부 판정), 바인딩(구문/데이터 분리)의 역할을 독립 적용하는 설계 원칙.

</details>

| 처리 단계 | 역할 | 주의점 |
|:---|:---|:---|
| **정규화** | 중복 표현을 단일 형식으로 통일 | 검증 단계 이전에 실행하여 우회 필터링 방지 |
| **입력값 검증** | 업무 허용 범위•형식 판정 | 출력 문맥별 엔티티 인코딩을 별도로 적용 |
| **파라미터 바인딩** | 실행 구문과 값을 분리 | **동적 식별자**는 허용 목록으로 매핑 통제 |

#### 한줄 요약

- 표현 디코딩 정규화, 허용목록 입력 검증, 구문 데이터 격리 파라미터 바인딩을 연계 분담함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **MITRE CWE-20**: 부적절한 입력 검토(Improper Input Validation) 약점 명세.
- **OWASP ASVS 5.0.0**: 입력 검증, 인코딩, 파라미터 바인딩 요구사항을 명시한 검증 표준.
- **객체 관계 매핑(Object-Relational Mapping, ORM)**: JPA, MyBatis 등 DB 쿼리를 안전하게 파라미터화 바인딩해주는 프레임워크.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 입력 검증 미비로 악성 데이터 침투 | **MITRE CWE-20** 준수 백엔드 허용목록 검증 | 비정상 입력값 선제 차단 |
| 검증과 출력 인코딩 혼동 | **OWASP ASVS 5.0.0** 지침 적용 | 입력 검증과 출력 인코딩 다계층 통제 |
| 동적 식별자 및 ORM 쿼리 취약성 | **ORM** 파라미터 바인딩 및 **허용 목록** 사전 매핑 | SQL 인젝션 및 데이터 훼손 차단 |

#### 한줄 요약

- 백엔드 허용목록 검증을 기본으로 적용하고, 쿼리 처리 시 ORM 파라미터 바인딩을 활성화함.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **입력 통제 적용 기준(Input Control Criteria)**: 서버 측 허용목록 검증, PreparedStatement 파라미터 바인딩, 동적 인자 매핑을 규정한 전사 가이드라인.

</details>

- **입력 통제 적용 기준**에 따라 외부 입력 데이터는 **허용 목록** 검증 및 **파라미터 바인딩**을 전면 적용.

#### 한줄 요약

- 입력값 검증 및 PreparedStatement 파라미터 바인딩 연계 통제 체계 구축 필수.
