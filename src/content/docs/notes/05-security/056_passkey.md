## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **패스키(Passkey / Multi-Device FIDO Credentials)**: FIDO2/WebAuthn 표준 공개키 암호화 기술을 기반으로 사용자의 패스워드를 완전히 대체하며, 종단간 암호화(E2EE: End-to-End Encryption)를 통해 사용자의 신뢰 클라우드 생태계(Apple iCloud Keychain, Google Password Manager, Microsoft Account) 내 등록된 여러 기기 간에 안전하게 자동 동기화되는 차세대 디지털 자격증명 기술.
- **단일 기기 종속 한계(Single-Device Lockout Defect)**: 기존 1세대 FIDO2 하드웨어 보안키는 개인키가 단일 칩셋에 물리적으로 고정되어 기기 분실·파손 시 사용자의 계정 접근이 영구 잠금되거나 복구 비용이 과도하게 발생하는 사용성 한계를 내포.

</details>

- 정의/개념: 비대칭 공개키 암호화의 **피싱 저항성(Phishing Resistance)** 과 클라우드 키체인의 **E2EE 다중 기기 동기화 및 백업 편의성** 을 결합하여 **패스워드리스(Passwordless) 인증 전환** 을 완성하는 **사용자 인증 아키텍처**
- 배경/필요성: 기기 결합 FIDO2는 개인키를 단일 보안칩 밖으로 내보내지 않는 대가로 기기 분실을 곧 계정 영구 잠금으로 만들고 기기마다 등록 절차를 되풀이하는 비용을 남기므로, 개인키를 사용자만 열 수 있는 형태로 암호화해 **E2EE 클라우드 키체인**이라는 사본 계층에 올려 이동성과 복구를 대신 떠맡길 필요

#### 한줄 요약
- FIDO2 공개키 비대칭 서명과 E2EE 클라우드 동기화를 결합하여 피싱 저항성과 기기 간 편의성을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **동기화 패스키(Synced Passkey / Multi-Device Credentials)**: 개인키가 사용자의 클라우드 키체인에 종단간 암호화되어 보관되며, 동일한 계정으로 로그인된 스마트폰, 태블릿, PC 간에 자동 복제되어 사용할 수 있는 소비자 지향형 패스키.
- **기기 결합 패스키(Device-Bound Passkey / Single-Device Credentials)**: 개인키가 물리적 보안 하드웨어 칩셋(TPM, HSM, YubiKey) 밖으로 절대 반출되지 않도록 고정되어, 금융권 및 국방/엔터프라이즈 미션 크리티컬 환경에 요구되는 최고 수준의 보안 패스키.

</details>

- **구조적 피싱 저항성 (Phishing Resistance)**: 브라우저와 OS가 현재 접속한 도메인(Origin)과 사전에 등록된 RP ID를 엄격히 대조하므로 피싱 사이트에서의 위조 서명 불가
- **엔드투엔드 암호화 동기화 (E2EE Sync)**: 클라우드 서비스 제공자(Apple, Google, MS)조차 사용자의 FIDO 개인키를 평문으로 복호화할 수 없는 제로 지식(Zero-Knowledge) 아키텍처
- **로컬 생체인식 연동 (UV: User Verification)**: 패스키를 사용한 서명 생성 시 기기 로컬의 생체인식(Touch ID, Face ID, Windows Hello) 또는 PIN을 필수 검증

#### 한줄 요약
- 패스키는 개인키를 기기 밖으로 내보내지 않는다는 FIDO2의 원칙을 E2EE 동기화로 완화한 결과이므로, 얻어 낸 이동성만큼 신뢰의 무게가 단말에서 클라우드 계정으로 옮겨 간다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **E2EE 클라우드 키체인(Cloud Keychain / KMS)**: 사용자 디바이스의 하드웨어 보안 모듈과 연동되어 생성된 복호화 키로 개인키를 암호화한 후 클라우드 저장소에 동기화하는 보안 아키텍처.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. Relying Party (RP 서버: 웹/모바일 서비스 백엔드) ]                 │
│  ├─ WebAuthn 챌린지 난수 생성 및 RP ID(`service.com`) 명시               │
│  └─ 자격증명 DB: 사용자 계정별 등록된 패스키 공개키(Public Key) 보관     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (1. 챌린지 전송 / HTTPS)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 클라이언트 플랫폼 및 브라우저 (OS Passkey Manager) ]               │
│  ├─ 도메인 Origin 검증 ➔ 가짜 피싱 사이트 진입 시 패스키 UI 호출 거부   │
│  └─ OS 통합 패스키 매니저 UI 팝업 (Apple / Google / Windows Hello)      │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (2. 로컬 생체 검증 UV 통과)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 하드웨어/클라우드 자격증명 엔진 (Passkey Engine) ]                 │
│  ├─ 보안칩(Secure Enclave) 내부 개인키로 챌린지 전자서명(Assertion) 수행 │
│  └─ [ E2EE 동기화: 새 기기 등록 시 클라우드 키체인을 통해 개인키 복제 ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (3. 전자서명 반환)
                                     ▼
[ RP 서버 ➔ 등록된 공개키로 서명 검증 성공 시 패스워드리스 로그인 승인 ]
```

선의 의미: RP 서버의 챌린지를 브라우저가 수신하여 도메인을 검증하고, OS 패스키 매니저에서 생체 검증 후 서명하여 RP 서버에서 공개키로 승인받는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **RP 서버 (Relying Party)** | WebAuthn 표준 기반으로 패스키 등록/인증 챌린지 발급 및 공개키 서명 검증 | WebAuthn Server|
| **OS 패스키 매니저** | 브라우저와 OS에 내장되어 패스키 UI 제공, 도메인(Origin) 검증 및 키 선택 중계 | Platform Provider|
| **생체인식 모듈 (UV)** | 사용자의 지문, 안면(FaceID), 기기 PIN을 로컬에서 검증하여 개인키 사용 인가 | User Verification|
| **보안 하드웨어 (TPM/SE)**| 비대칭 개인키를 격리 보관하고 암호학적 비가역 전자서명을 실행 | Secure Storage |
| **E2EE 동기화 키체인** | 암호화된 개인키를 동일 계정의 다중 디바이스(스마트폰, 태블릿, PC)에 안전 동기화 | Cloud Sync |

#### 한줄 요약
- 앞의 네 요소는 FIDO2와 동일하고 E2EE 키체인만이 새로 끼어든 계층이며, 그 계층이 분실 복구를 떠맡는 대신 클라우드 계정을 새로운 단일 장애점이자 공격 표면으로 만든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **패스키 등록 vs 인증 수명주기**:
  - **등록(Registration)**: 기기에서 비대칭 키쌍(KeyPair)을 생성하고, 개인키는 보안칩/키체인에 보관하며 공개키만 RP 서버로 전송하여 매핑.
  - **인증(Authentication)**: RP 서버의 챌린지를 수신하여 로컬 생체인증 후 개인키로 서명하여 RP 서버로 전송.

</details>

```text
1. [인증 시작] 사용자가 서비스 접속 후 "패스키로 로그인" 선택 ➔ RP 서버가 일회용 챌린지와 `rpId` 발행
            │
            ▼
2. [도메인 무결성 확인] 브라우저가 현재 사이트의 `Origin`을 추출하여 RP ID와 일치성 검증 (피싱 사이트 차단)
            │
            ▼
3. [생체 기반 사용자 검증] OS 패스키 매니저가 팝업을 띄우고 사용자의 지문/FaceID 생체인식(UV) 집행
            │
            ▼
4. [개인키 서명 생성] 디바이스 내부 보안 영역에 보관된 개인키로 챌린지 데이터에 대한 전자서명 생성
            │
            ▼
5. [RP 서버 검증 및 인가] RP 서버가 사전에 등록된 사용자의 공개키로 서명을 복호화 대조 ➔ [패스워드리스 세션 발급]
```

**동작 원리**

1. **지식 기반 비밀정보 배제**: 비밀번호 입력 절차를 완전히 생략하여 메모리 덤프 및 키로깅 위험 제거
2. **출처 기반 서명 강제**: 올바른 서비스 도메인에서만 암호학적 서명이 생성되도록 브라우저 런타임 제어
3. **로컬 무결성 보증**: 생체 데이터가 네트워크로 전송되지 않고 기기 내부에서만 일치성 평가
4. **자격증명 이동성(Mobility)**: E2EE 클라우드 동기화를 통해 단일 기기 고장 시에도 계정 연속성 보장
5. **폐쇄 루프 검증 관리**: 비대칭 공개키 서명의 수학적 검증을 통해 위변조 불가능한 인증 세션 확립

#### 한줄 요약
- 인증 흐름 자체는 FIDO2와 같고 갈리는 지점은 개인키가 어디에 몇 벌 존재하느냐뿐이므로, 패스키 선택은 인증 강도의 문제가 아니라 복구 편의와 복제 위험 사이의 조정이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **패스키 3대 자격증명 보관 방식 비교**: 동기화 패스키(소비자 편의), 기기 결합 패스키(엔터프라이즈), 외장 하드웨어 보안키(에어갭/고위험)의 비교.

</details>

| 비교 항목 | 동기화 패스키 (Synced Passkey) | 기기 결합 패스키 (Device-Bound) | 외장 하드웨어 보안키 (YubiKey) |
|:---|:---|:---|:---|
| **개인키 보관 및 동기화** | **E2EE 클라우드 키체인 다중 기기 동기화**| **특정 단일 기기 내장 TPM/SE에 고정** | **외장 USB/NFC 보안 토큰 하드웨어 고정**|
| **주요 대상 타깃** | **일반 B2C 대고객 서비스, 범용 포털** | **B2B 기업 인프라, 관리자 단말** | **금융 거래 인가, 국방 및 망분리 환경**|
| **사용자 편의성 (UX)** | **최상 (기기 교체 시 자동 복원 지원)** | 보통 (기기마다 개별 등록 절차 필요) | 낮음 (물리적 키를 상시 휴대 및 연결) |
| **자격증명 탈취 위협** | 클라우드 마스터 계정 침해 시 복제 위험| **원격 탈취 완전 불가 (물리 단말 종속)** | **완벽한 물리적 에어갭 격리 보장** |
| **기기 분실 시 복구** | **클라우드 계정 인증을 통해 즉시 복원**| 별도의 비상 복구(Recovery) 절차 필수 | 백업 하드웨어 키로 재등록 필요 |

#### 한줄 요약
- 셋은 개인키의 사본을 몇 벌 어디에 두느냐의 차이이며, 사본을 늘릴수록 분실 복구는 쉬워지고 탈취 표면은 넓어지므로 선택은 계정 가치와 복구 비용의 비교로 귀결된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **자격증명 폐기(Credential Revocation)**: 단말기 분실, 도난, 직원 퇴사 시 RP 서버의 데이터베이스에서 해당 기기에 할당된 패스키 공개키 레코드를 즉시 삭제하여 접근을 차단하는 라이프사이클 관리.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동기화 패스키 사용자의 애플/구글 클라우드 계정이 탈취되어 **모든 연동 서비스의 패스키가 공격자 기기로 불법 복제** | **NIST SP 800-63B** 준수, 클라우드 마스터 계정에 대한 **하드웨어 2차 인증(MFA) 및 비정상 동기화 탐지** 강제 | 마스터 계정 장악 방어 및 비인가 다중 기기 패스키 불법 동기화 100% 차단 |
| 기기 결합 패스키 환경에서 사용자가 유일한 등록 단말을 분실하여 **계정이 영구 잠금(Account Lockout)되는 장애** | **최초 등록 시 2대 이상의 디바이스 등록을 강제하고 엄격한 신원 확인 기반의 계정 복구(Recovery) 절차 수립** | 단일 장애점(SPOF) 해소 및 업무 연속성 99.99% 보장 |
| 직원이 퇴사한 후에도 개인 스마트폰에 동기화된 사내 패스키를 이용하여 **기업 내부망에 무단 접속하는 보안 사고** | **퇴사 및 단말 분실 처리 시 IAM/RP 서버에서 해당 사용자의 패스키 공개키를 즉시 폐기(Revoke) 처리** | 미인가 잔존 자격증명을 통한 내부 시스템 무단 침투 경로 100% 원천 봉쇄 |

#### 한줄 요약
- 마스터 계정 MFA로 복제를 막고, 복수 등록으로 분실 잠금을 방지하며, 퇴사 시 공개키를 즉시 폐기한다.

## Ⅶ. 결론

- 소비자는 **동기화 패스키**, 고위험 계정은 기기 결합형과 복구 통제 적용

#### 한줄 요약
- FIDO2 비대칭 서명과 E2EE 동기화 및 라이프사이클 폐기 관리를 통해 안전한 패스키 생태계를 완성한다.
