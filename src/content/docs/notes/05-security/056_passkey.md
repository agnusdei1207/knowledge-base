## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **패스키**: 서비스별 공개키 자격 증명으로 비밀번호를 대신하는 피싱 저항 인증 수단이다.
- **웹 인증(Web Authentication, WebAuthn)**: 브라우저를 통한 공개키 자격 증명의 등록•인증을 정의하는 표준이다.

</details>

- 정의/개념: **패스키**는 **WebAuthn** 기반의 서비스별 공개키 인증 수단이다.
- 배경/필요성: 비밀번호는 피싱•재사용•서버 유출 위험이 있다.

#### 한줄 요약

- 사용자는 기기 잠금을 풀듯 승인하고 서비스는 비밀번호 대신 자기 사이트에만 맞는 공개키 서명을 확인한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **신뢰 당사자 식별자(Relying Party Identifier, RP ID)**: 패스키를 특정 서비스 도메인에 결속하는 식별자이다.
- **사용자 검증**: 인증기 사용자가 등록된 본인인지 생체•PIN 등으로 확인하는 절차이다.
- **신뢰 당사자(Relying Party, RP)**: 패스키의 공개키를 등록하고 인증 서명을 검증하는 서비스이다.
- **동기화 패스키**: 암호화된 자격 증명을 사용자의 여러 기기로 이전하는 방식이다.
- **기기 결합 패스키**: 자격 증명을 생성한 특정 인증자에 고정하는 방식이다.

</details>

- **RP ID**와 서비스 원본에 공개키를 결속해 피싱 사이트의 재사용을 차단한다.
- **동기화 패스키**는 기기 이전성을, **기기 결합 패스키**는 이동 제한을 우선한다.
- **RP**는 등록•인증뿐 아니라 기기 추가•복구•세션 폐기 정책도 집행한다.

#### 한줄 요약

- 패스키 자체는 피싱에 강하지만 등록•복구 절차가 약하면 공격자가 계정을 탈취할 수 있다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **인증자**: 개인키를 보호하고 PIN•생체 승인 후 서명하는 장치•소프트웨어이다.
- **개인 식별 번호(Personal Identification Number, PIN)**: 인증기 안의 개인키 사용을 승인하는 번호이다.
- **복구 경로**: 기기 분실•교체 뒤 계정 접근을 되찾는 절차이다.

</details>

```text
패스키 인증 구조
├─ RP 서버: 도전값 발급•공개키 검증
├─ 플랫폼•브라우저: 원본 확인•요청 중계
├─ 인증자: 개인키 보호•서명 생성
├─ 사용자 검증: PIN•생체로 키 사용 승인
└─ 동기화•복구 체계: 기기 이전•분실 대응
```

| 구성요소 | 책임 |
|:---|:---|
| RP 서버 | 도전값 발급•공개키 검증 |
| 플랫폼•브라우저 | 원본 확인•인증 요청 중계 |
| 인증자 | **인증자**의 개인키 보호•서명 생성 |
| 사용자 검증 | **PIN**•생체로 키 사용 승인 |
| 동기화•복구 체계 | **복구 경로**로 기기 이전•분실 대응 |

#### 한줄 요약

- 서버가 새 질문을 보내면 플랫폼이 올바른 사이트인지 확인하고 인증자가 사용자 승인 후 서명한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **도전값•RP ID 생성**: 서버가 일회성 난수와 자격 증명 서비스 경계를 구성하는 단계이다.
- **원본•RP ID 검증**: 현재 사이트 출처와 자격 증명의 서비스 결속을 확인하는 단계이다.
- **PIN•생체 사용자 검증**: 로컬 인증기가 개인키 사용자를 확인하는 단계이다.
- **서비스별 개인키 서명**: 인증기가 해당 서비스 전용 개인키로 도전값과 문맥에 서명하는 단계이다.
- **도전값•공개키 서명 검증**: 서버가 일회성 값과 등록 공개키를 이용해 응답의 진위를 판정하는 단계이다.

</details>

```text
인증 요청
    |
    v
1. 도전값•RP ID 생성
    |
    v
2. 원본•RP ID 검증
    |
    v
3. PIN•생체 사용자 검증
    |
    v
4. 서비스별 개인키 서명
    |
    v
5. 도전값•공개키 서명 검증
    |
    +-- 불일치 -- 인증 거부
    |
    +-- 일치 -- 인증 성공
```

### 동작 원리

1. **도전값•RP ID 생성**: 일회성 값과 자격 증명 서비스 경계로 도전값•RP ID를 생성한다.
2. **원본•RP ID 검증**: 현재 사이트와 자격 증명 결속에 대해 원본•RP ID 검증을 수행한다.
3. **PIN•생체 사용자 검증**: 로컬에서 개인키 사용자를 PIN•생체로 검증한다.
4. **서비스별 개인키 서명**: 비노출 키로 도전값•문맥에 서비스별 개인키 서명을 생성한다.
5. **도전값•공개키 서명 검증**: 서버가 도전값•공개키 서명을 검증해 재전송•위조 응답을 거부한다.


#### 한줄 요약

- 기기에서 본인을 확인해도 생체 정보는 서버로 가지 않고 승인된 개인키의 서명 결과만 전달된다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **휴대형 보안키**: 개인키를 별도 물리 장치에 보관하는 외부 인증자이다.
- **패스키 보관 방식 선택 기준**: 편의•복구는 동기화, 이동 제한은 기기 결합, 물리 분리는 휴대형 보안키를 선택하는 판단 기준이다.

</details>

| 패스키 보관 방식 | 공통 | 동기화 패스키 | 기기 결합 패스키 | 휴대형 보안키 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 비밀번호 대체 | 소비자 편의•복구 | 조직의 이동 제한 | 강한 물리 분리 |
| 핵심 특징 | **패스키**의 서비스별 공개키 인증 | **동기화 패스키**의 여러 기기 이전 | **기기 결합 패스키**의 특정 기기 고정 | **휴대형 보안키**의 별도 물리 장치 사용 |
| 한계 | 약한 대체 로그인 | 동기화 계정 탈취 | 분실 시 복구 부담 | 배포•회수•예비 키 필요 |

#### 한줄 요약

- **패스키 보관 방식 선택 기준**으로 동기화, 기기 결합, 별도 보안키 중 운영 목적에 맞춰 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **W3C WebAuthn Level 2**: RP에 결속된 공개키 자격 증명의 등록•인증 규격이다.
- **NIST SP 800-63B-4**: 인증기•세션•복구 요구를 정의하는 미국 국립표준기술연구소 지침이다.
- **자격 증명 폐기**: 분실•유출된 패스키를 더 이상 인증에 쓰지 못하게 하는 통제이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| RP•원본•서명 검증 오류로 피싱•재전송 허용 | **W3C WebAuthn Level 2** 준수 | 피싱•재전송 저항성 확보 |
| 동기화 계정 탈취로 여러 기기의 패스키 노출 | **NIST SP 800-63B-4** 적용 | 동기화•세션의 인증 위험 통제 |
| 단일 기기 분실•약한 복구로 잠금•계정 탈취 | 복수 인증자•강한 복구와 **자격 증명 폐기** 적용 | 분실 자격 증명 재사용 방지 |

#### 한줄 요약

- 사용자는 새 휴대전화에서도 플랫폼 계정을 통해 동기화된 패스키를 복원해 비밀번호 없이 서비스에 로그인한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **전환 완성 조건**: 비밀번호 제거뿐 아니라 기기 추가•동기화•분실 복구를 같은 강도로 보호하는 조건이다.
</details>

- **전환 완성 조건**을 지키며 소비자 편의는 **동기화 패스키**, 이동 제한은 **기기 결합 패스키**, 물리 분리는 **휴대형 보안키**를 선택한다.

#### 한줄 요약

- 패스키 전환은 비밀번호 제거로 끝나지 않으며 기기 추가•동기화•분실 복구를 같은 인증 강도로 설계해야 완성된다.
