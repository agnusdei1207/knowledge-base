## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **패스키(Passkey)**: FIDO2/WebAuthn 표준 기반으로 사용자 비밀번호를 대체하며, 종단간 암호화(E2EE)를 통해 클라우드 계정 간 안전하게 동기화되는 디지털 자격증명.
- **웹 인증(Web Authentication, WebAuthn)**: 브라우저와 RP 서버 간 패스키 등록 및 공개키 서명 인증을 처리하는 W3C 웹 API 규격.

</details>

- 정의/개념: 공개키로 비밀번호를 대체하는 **패스키**
- 배경/필요성: 비밀번호는 **재사용•피싱 유출**에 취약

#### 한줄 요약

- 서비스별 비대칭 공개키 서명과 종단간 암호화 동기화를 결합하여 비밀번호 없는 Passwordless 인증을 구현함.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **신뢰 당사자 식별자(Relying Party ID, RP ID)**: 패스키를 특정 웹 서비스 도메인에 고정 바인딩하는 식별값.
- **사용자 검증(User Verification, UV)**: 인증기 자체 생체인식 센서 또는 PIN 입력을 통해 실제 소유자가 본인임을 검증하는 절차.
- **신뢰 당사자(Relying Party, RP)**: 패스키 공개키를 저장하고 서명 검증을 집행하는 백엔드 애플리케이션.
- **동기화 패스키(Synced Passkey)**: Apple iCloud 키체인, Google 비밀번호 관리자 등을 통해 동일 계정의 다중 디바이스 간 종단간 암호화(E2EE) 동기화되는 패스키.
- **기기 결합 패스키(Device-bound Passkey / Hardware Key)**: YubiKey 등 특정 하드웨어 보안 칩셋 밖으로 유출 및 이전이 불가능한 패스키.

</details>

- **RP ID**와 도메인 원본(Origin) 결속을 통한 중간자 역프록시 피싱 사이트 공격 원천 차단.
- 소비자 편의 중심의 **동기화 패스키(Synced Passkey)**와 높은 보안 수준의 **기기 결합 패스키(Device-bound Passkey)** 지원.
- 생체인식 기반 **사용자 검증(UV)** 및 물리 조작 **사용자 존재(UP)**에 의한 2차 인증 결합.

#### 한줄 요약

- **RP ID 결속•E2EE 동기화•UV**로 비밀번호 대체

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인증자(Authenticator)**: 플랫폼 OS 보안 가상화 영역(Secure Enclave/TPM)에 개인키를 안전하게 생성 및 보관하는 컴포넌트.
- **개인 식별 번호(Personal Identification Number, PIN)**: 생체 인식 실패 또는 비지원 기기에서 로컬 개인키 서명을 승인하기 위해 입력하는 비밀 키.
- **복구 경로(Account Recovery Flow)**: 디바이스 전량 분실 시 계정 접근권을 되찾기 위한 대체 본인확인 절차.

</details>

```text
패스키 인증 구조
├─ RP 서버: 도전값 발급•공개키 검증
├─ 플랫폼•브라우저: 원본 확인•요청 중계
├─ 인증자: 개인키 보호•서명 생성
├─ 사용자 검증: PIN•생체로 키 사용 승인
└─ 동기화•복구 체계: 기기 이전•분실 대응
```

| 구성요소 | 책임 |
|:---|:---|
| RP 서버 | Challenge 발급, 패스키 공개키 DB 수신 저장 및 서명 판정 |
| 플랫폼•브라우저 | **Origin** 도메인 대조 및 패스키 선택 UI 제공 |
| 인증자 | **인증자(Authenticator)** 보안 영역 내부 개인키 저장 및 서명 생성 |
| 사용자 검증 | 생체인식 및 **PIN** 입력을 통한 로컬 키 사용 승인 |
| 동기화•복구 체계 | E2EE 키체인 동기화 및 **복구 경로**를 통한 기기 교체 대응 |

#### 한줄 요약

- RP 서버, 플랫폼 브라우저, 보안 인증자, 생체 UV 검증 및 E2EE 클라우드 동기화 구조로 구성됨.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **도전값•RP ID 생성**: RP 서버가 일회성 Challenge 난수 및 RP ID 조건 전달 단계.
- **원본•RP ID 검증**: 브라우저 파서가 접속 도메인과 RP ID의 동일성을 대조하는 단계.
- **PIN•생체 사용자 검증**: 사용자가 생체 터치 또는 PIN을 입력하여 로컬 인가를 완료하는 단계.
- **서비스별 개인키 서명**: 인증자 내부 개인키로 Challenge + ClientData에 서명하는 단계.
- **도전값•공개키 서명 검증**: RP 서버가 저장된 패스키 공개키로 서명의 정당성을 검증하는 단계.

</details>

```text
인증 요청
    │
    ▼
1. 도전값•RP ID 생성
    │
    ▼
2. 원본•RP ID 검증
    │
    ▼
3. PIN•생체 사용자 검증
    │
    ▼
4. 서비스별 개인키 서명
    │
    ▼
5. 도전값•공개키 서명 검증
    │
    ├─ 불일치 ── 인증 거부
    │
    └─ 일치 ── 인증 성공
```

### 동작 원리

1. **도전값•RP ID 생성**: RP 서버에서 일회성 Challenge 및 RP ID 정의.
2. **원본•RP ID 검증**: 브라우저 런타임 상에서 **Origin**과 **RP ID** 상호 대조.
3. **PIN•생체 사용자 검증**: 디바이스 로컬 상에서 지문/얼굴 생체인식(UV) 집행.
4. **서비스별 개인키 서명**: 디바이스 내부 **개인키**로 Challenge 문맥 전자서명 생성.
5. **도전값•공개키 서명 검증**: RP 서버에서 **공개키** 서명 검증 및 무상태 로그아웃/세션 생성.

#### 한줄 요약

- Challenge 생성, RP ID 도메인 검증, 생체인식 UV, 개인키 전자서명 및 공개키 검증으로 구동함.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **휴대형 보안키(Hardware Security Key)**: USB/NFC 형태의 물리적 YubiKey 보안키.
- **패스키 보관 방식 선택 기준(Passkey Storage Selection Criteria)**: 편의성과 복구 위주는 동기화 패스키, 높은 보안 하드닝은 기기 결합 패스키/보안키를 적용하는 가이드라인.

</details>

| 패스키 보관 방식 | 동기화 패스키 | 기기 결합 패스키 | 휴대형 보안키 |
|:---|:---|:---|:---|
| 적용 기준 | 일반 사용자 B2C 서비스 | 기업 내부 B2E 보안 환경 | High-Value 전용 관리자 환경 |
| 핵심 특징 | Apple/Google E2EE 클라우드 동기화 | 특정 디바이스 TPM 밖 이전 불가 | USB/NFC 기반 물리 하드웨어 저장 |
| 한계 | 클라우드 계정 유출 시 연쇄 위험 | 기기 분실 시 복구 절차 필요 | 배포/구매 비용 및 휴대 불편성 |

#### 한줄 요약

- 멀티 기기 동기화 패스키, 디바이스 고정 패스키 및 물리 하드웨어 보안키를 서비스 위험도에 맞게 선택함.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C WebAuthn Level 2**: 패스키 등록 및 검증을 지원하는 웹 인증 레벨 표준.
- **NIST SP 800-63B-4**: 디지털 자격증명 관리 및 패스워드리스 적용 표준 가이드.
- **자격 증명 폐기(Credential Revocation)**: 디바이스 분실 시 RP 서버 상에서 등록된 패스키 공개키를 무효화하는 관리 기능.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 브라우저/OS별 패스키 호환성 | **W3C WebAuthn Level 2** 스펙 완벽 준수 | 크로스 플랫폼 패스키 연동성 확보 |
| 클라우드 동기화 계정 탈취 위협 | **NIST SP 800-63B-4** 기준 동기화 계정 MFA 강화 | 패스키 무단 복제 및 재전송 차단 |
| 단일 디바이스 분실 시 계정 잠금 | 복수 패스키 사전 등록 및 **자격 증명 폐기** 관리 | 분실 패스키 무효화 및 안전한 계정 복구 |

#### 한줄 요약

- W3C WebAuthn 표준을 준수하고, 동기화 계정 MFA 적용 및 분실 시 자격증명 폐기 기능을 연동함.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **전환 완성 조건(Passkey Migration Completion)**: 비밀번호 입력을 전면 제거하는 동시에, 패스키 등록/복구 경로에 본인확인을 동등 보증 수준으로 적용하는 기준.

</details>

- **전환 완성 조건**에 입각하여 B2C 서비스는 **동기화 패스키**, B2E 보안 환경은 **기기 결합 패스키** 및 **자격 증명 폐기** 시스템 구축.

#### 한줄 요약

- B2C는 **동기화 패스키**, B2E는 **기기 결합 패스키** 선택
