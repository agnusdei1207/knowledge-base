## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **키 관리(Key Management)**: 암호키의 생성•보관•배포•사용•교체•폐기를 수명주기 전체에서 통제하는 활동이다.
- **루트 키(Root Key)**: 하위 키를 보호하며 조직 암호체계의 최상위 신뢰점이 되는 키이다.

</details>

- 정의/개념: **키 관리**는 **루트 키**를 포함한 암호키의 생성부터 폐기까지 이어지는 수명주기 통제이다.
- 배경/필요성: 응용이 키를 직접 보관하면 노출•권한•사용 이력을 통제하기 어렵다.

#### 한줄 요약

- 안전한 암호 알고리즘도 키가 노출되면 보호 효과를 잃으므로 생성부터 폐기까지 키의 전체 수명주기를 통제해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **데이터 암호화 키(Data Encryption Key, DEK)**: 실제 데이터를 암호화하는 하위 대칭키이다.
- **키 암호화 키(Key Encryption Key, KEK)**: DEK 등 다른 키를 보호하는 상위 키이다.
- **하드웨어 보안 모듈(Hardware Security Module, HSM)**: 암호키를 외부로 노출하지 않고 내부에서 암호 연산을 수행하는 보안 장비이다.
- **키 관리 시스템(Key Management System, KMS)**: 암호키의 정책•권한•버전•수명주기와 사용 이력을 관리하는 시스템이다.

</details>

- **KEK**와 **DEK**를 분리하여 키 노출 범위를 줄인다.
- **HSM** 내부에서 키를 생성•사용하여 원본 키를 반출하지 않는다.
- **KMS**가 정책•권한•버전과 수명주기를 통제한다.

#### 한줄 요약

- HSM은 키 원본과 암호 연산을 물리적으로 보호하고, KMS는 키를 누가 언제 어떤 용도로 사용할지 정책과 이력으로 통제한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **신원•접근 관리(Identity and Access Management, IAM)**: 사용자와 서비스의 신원을 확인하고 자원 접근 권한을 통제하는 체계이다.
- **키 래핑(Key Wrapping)**: 한 암호키로 다른 암호키의 기밀성과 무결성을 보호하는 처리이다.

</details>

```text
키 관리 구조
├─ KMS•IAM
├─ HSM•KEK
├─ DEK
└─ 키 메타데이터
```

가지의 의미: 정책•상위 키•데이터 키•상태 기록 책임을 나눈 구조다.

| 구성요소 | 책임 |
|:---|:---|
| KMS•IAM | **KMS**와 **IAM**으로 정책•접근 권한 통제 |
| HSM•KEK | **HSM**에서 **KEK**와 암호 연산 보호 |
| DEK | **DEK**로 실제 데이터 암호화 |
| 키 메타데이터 | 상태•버전•사용 이력 기록 |


#### 한줄 요약

- 데이터는 DEK로 암호화하고 DEK는 KEK로 래핑하며, KEK는 HSM 외부로 노출하지 않는다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **봉투 암호화(Envelope Encryption)**: DEK로 데이터를 암호화하고 KEK로 DEK를 다시 암호화하는 방식이다.
- **제로화(Zeroization)**: 암호키를 메모리와 저장매체에서 복구할 수 없도록 삭제하는 처리이다.
- **IAM•키 정책 검증**: 요청 주체•용도•권한과 대상 키의 상태를 정책에 대조하는 단계이다.
- **DEK 생성•KEK 래핑**: 새 데이터 키를 생성하고 상위 키로 기밀성과 무결성을 보호하는 단계이다.
- **데이터 암호화**: 평문 DEK를 메모리에서만 사용하여 데이터를 암호문으로 바꾸는 단계이다.
- **암호문•래핑 DEK 저장**: 암호화한 데이터와 KEK로 보호한 DEK를 함께 보관하는 단계이다.
- **평문 DEK 제로화**: 암호화를 마친 평문 DEK를 메모리에서 복구할 수 없게 제거하는 단계이다.

</details>

```text
DEK 생성 요청
        │
        ▼
1. IAM•키 정책 검증
        ├─ 실패: 키 사용 거부
        └─ 성공
             │
             ▼
     2. DEK 생성•KEK 래핑
             │
             └── 평문 DEK 임시 제공
                         │
                         ▼
                 3. 데이터 암호화
                         │
                         ▼
                 4. 암호문•래핑 DEK 저장
                         │
                         ▼
                 5. 평문 DEK 제로화
```

### 동작 원리

1. **IAM•키 정책 검증**: **IAM**으로 주체•용도•권한•키 상태를 확인한다.
2. **DEK 생성•KEK 래핑**: **키 래핑**으로 데이터 키를 상위 키로 보호한다.
3. **데이터 암호화**: 평문 DEK를 메모리에서만 사용한다.
4. **암호문•래핑 DEK 저장**: **봉투 암호화** 결과를 보관한다.
5. **평문 DEK 제로화**: **제로화**로 사용 완료 키를 메모리에서 제거한다.


#### 한줄 요약

- 키의 생성•배포•사용•회전•폐기 단계마다 권한을 검증하고 감사 이력을 남긴다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **비밀 관리기(Secret Manager)**: 비밀번호•토큰•API 키 등 응용 비밀정보의 저장•배포•회전을 관리하는 서비스이다.

</details>

| 키 관리 수단 | HSM | KMS | Secret Manager |
|:---|:---|:---|:---|
| 적용 기준 | 루트 키 보호 | 키의 중앙 수명주기 관리 | 응용 비밀 배포 |
| 핵심 특징 | **HSM**으로 키•연산 장비 보호 | **KMS**로 키 수명주기 통제 | **비밀 관리기**로 비밀번호•토큰 보관 |
| 한계 | 장비 장애 | 권한 정책 오류 | 응용의 비밀 노출 |

> 요약: HSM은 보안 경계이고 KMS는 수명주기 통제 수단이다.

#### 한줄 요약

- HSM은 키의 물리적 보호, KMS는 키 수명주기 통제, 비밀 관리기는 응용 자격정보 관리를 담당하므로 역할에 맞게 결합한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **이중 통제(Dual Control)**: 중요 작업에 둘 이상의 독립된 승인을 요구하는 원칙이다.
- **분할 지식(Split Knowledge)**: 한 사람이 전체 비밀을 알지 못하도록 나누는 원칙이다.
- **미국 국립표준기술연구소(National Institute of Standards and Technology, NIST)**: 미국의 기술 표준과 지침을 개발하는 기관이다.
- **특별 간행물(Special Publication, SP) 800-57 Part 1 Rev. 5**: 키 수명주기 지침을 제시하는 문서이다.
- **연방 정보 처리 표준(Federal Information Processing Standards, FIPS) 140-3**: 암호 모듈 보안 요구사항을 제시하는 미국 연방 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 키 수명주기 불일치 | **NIST** **SP 800-57 Part 1 Rev. 5** 적용 | 생성•회전•폐기 일관화 |
| 암호 모듈 보호 부족 | **NIST** **FIPS 140-3** 검증 | 키 반출•변조 위험 억제 |
| 루트 키 오용 | **이중 통제**•**분할 지식** | 단일 관리자 남용 차단 |
| 폐기 키의 복구 가능성 | 메모리•매체 **제로화** 검증 | 폐기 후 키 노출 방지 |

#### 한줄 요약

- 루트 키 생성•백업•복구에는 이중 통제와 분할 지식을 적용하여 단일 관리자의 오용을 방지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **역할 분리**: HSM이 키의 보안 경계를, KMS가 키 수명주기 정책을 담당하도록 책임을 구분하는 원칙이다.

</details>

- **역할 분리**에 따라 루트•서명키는 **HSM**, 서비스 키 수명주기는 **KMS**를 선택한다.

#### 한줄 요약

- 알고리즘 강도만 확보해서는 충분하지 않으며, 키의 생성부터 폐기까지 권한•보관•회전•감사 통제가 이어져야 한다.
