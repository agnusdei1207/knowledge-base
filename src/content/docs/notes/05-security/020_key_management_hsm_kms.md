## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **키 관리 (Key Management)**: 암호키를 언제 만들고, 누구한테 주고, 언제 뺏어서 폐기할지(수명주기)를 깐깐하게 통제하는 인프라 사령부다.
- **루트 키 (Root Key)**: 모든 하위 암호키를 잠그는 최상위 마스터키다. 이 루트 키 하나가 침해당하면 회사 암호 체계 전체가 붕괴된다.

</details>

- 정의: 최고 마스터키(Root Key)를 기준으로 암호키의 생성, 보관, 배포, 폐기(수명주기) 전 과정을 하드웨어와 정책 기반으로 통제하는 체계다.
- 배경: 소스코드에 비밀번호를 박아두거나(하드코딩), 연산이 끝난 생 열쇠를 메모리(RAM)에 방치했다가 해커한테 다 침해당하는 참사가 빈번했기 때문이다.

#### 한줄 요약

- 아무리 자물쇠가 튼튼해도 열쇠를 길바닥에 흘리면 끝이다. 열쇠를 무쇠 금고에 넣고, 유통 기한을 정해 관리하는 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **DEK (데이터 암호화 키)**: 실제 대용량 DB나 파일을 빠르게 잠그는 실무 대칭키다.
- **KEK (키 암호화 키)**: 이 DEK 실무 열쇠 자체를 다시 잠가서(래핑) 보관하는 상위 보스 열쇠다.
- **HSM (하드웨어 보안 모듈)**: 상위 열쇠를 보관하는 철통 물리 금고 장비다. 누가 억지로 뜯으려고 하면 안의 열쇠를 녹여버린다(템퍼 저항성).
- **KMS (키 관리 시스템)**: 열쇠를 언제 갱신(회전)할지, 누가 썼는지 로그를 감시하는 소프트웨어 사령부다.

</details>

- **계층화 (봉투 암호화)**: 수천만 건의 데이터를 잠근 수많은 DEK를, 상위 KEK 하나로 다시 잠가서 포장(Envelope)하는 이중 보호 방식을 쓴다.
- **물리적 철저한 방어 (HSM)**: 최상위 키는 소프트웨어가 아닌 하드웨어 금고(HSM) 안에서만 연산되도록 가둬서 외부 유출을 원천 차단한다.
- **통합 통제 (KMS)**: 수만 개의 열쇠 접근 권한(IAM)을 통제하고 자동 갱신(Rotation)하며 쓴 내역을 모두 기록한다.

#### 한줄 요약

- 열쇠로 데이터를 잠그고 $\to$ 그 열쇠를 더 큰 열쇠로 또 잠가서(계층화) $\to$ 물리 금고(HSM)와 통제 시스템(KMS)으로 철통 철저한 방어한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **IAM (신원/접근 관리)**: "DB 서버는 암호화(Encrypt) 권한만 주고, 웹 서버는 복호화(Decrypt) 권한만 줘!" 하고 권한을 쪼개는 경비 시스템이다.
- **키 래핑 (Key Wrapping)**: 1급 열쇠(KEK)로 2급 열쇠(DEK)를 암호화해서 "열쇠를 담은 안전한 금고통"을 만드는 기술이다.

</details>

```text
[ 키 관리 인프라 및 봉투 암호화 구조 ]

[ 1. KMS 및 IAM 정책 ] ── ("웹서버는 이 열쇠 쓸 자격 있음!" 승인해 주고 기록 남김)
      │
      ▼
[ 2. HSM (KEK 보관) ] ── (절대 안 침해당하는 하드웨어 금고 안에서 상위 보스 열쇠 보관)
      │
      ▼ (HSM이 포장된 DEK를 뱉어냄)
[ 3. DEK (실무 데이터 키) ] ── (실제로 기가바이트 단위의 DB 데이터를 잠그고 푸는 열쇠)
      │
      ▼
[ 4. 키 메타데이터 ] ── ("이 열쇠는 어제 만들었고 내일 폐기됨" 수명주기 꼬리표 붙임)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **KMS 및 IAM 정책** | 누가 열쇠를 쓸 건지 **권한을 쪼개고, 열쇠 수명(회전)을 관리함** | Mgmt |
| **HSM (물리 금고)** | 최상위 보스 열쇠(KEK)를 **해킹 불가능한 쇳덩이 장비 안에서만 굴림** | Vault |
| **DEK (데이터 키)** | 빠른 속도로 **실제 대용량 데이터(DB, 파일)를 잠그고 푸는 실무 열쇠** | Data Key |
| **키 메타데이터** | 열쇠의 버전, 활성화 상태, 폐기 일자 등 **수명 이력을 꼬리표로 붙임** | Meta |

#### 한줄 요약

- 권한 검사소(KMS/IAM) $\to$ 무적 금고(HSM) $\to$ 실무 열쇠(DEK) $\to$ 꼬리표(메타데이터)로 이어지는 지휘 체계다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **봉투 암호화 (Envelope Encryption)**: 데이터를 DEK로 잠근 다음, 그 DEK를 KEK로 한 번 더 잠가서(래핑) 데이터 옆에 착 붙여서 저장하는 거다.

</details>

```text
[ 봉투 암호화(Envelope) 및 DEK 제로화 흐름 ]

┌──────────────────────────────┐
│ 1. [IAM 권한 검증 및 데이터 키 발급 요청]
│ ("KMS님, 나 앱 서버인데 데이터 잠글 열쇠(DEK) 좀 주소")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [DEK 생성 및 KEK 래핑 (HSM/KMS)]
│ (금고에서 쓸 수 있는 생 열쇠 1개와, 보관용으로 래핑(포장)된 열쇠 1개를 같이 줌)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [임시 메모리 상 데이터 암호화]
│ (서버 램(RAM)에서 생 열쇠로 민감 데이터를 빛의 속도로 암호화함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [데이터 암호문 + 래핑된 DEK 결합 저장]
│ (잠긴 데이터 덩어리 옆에 '래핑된 열쇠통'을 딱 붙여서 영구 저장소에 저장함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [메모리 상 평문 DEK 제로화 (Zeroization)]
│ (일 끝났으면 램에 남아있는 생 열쇠를 무작위 쓰레기값으로 덮어써서 파기함)
└──────────────────────────────┘
```

### 동작 원리

1. 정책 검증: KMS가 요청 주체의 IAM 권한(kms:GenerateDataKey 등)을 검증함.
2. 봉투 발급: HSM이 난수 DEK(생 열쇠)와 KEK로 래핑된 DEK(포장된 열쇠)를 동시 발급함.
3. 데이터 암호화: 앱 서버의 RAM 임시 구역에서 생 열쇠(DEK)로 대용량 암호화를 수행함.
4. 패킷 저장: 데이터 암호문과 래핑된 DEK를 스토리지에 합성하여 영구 보관함.
5. 제로화 소거: 연산 직후 RAM 상의 평문 DEK를 무작위 비트로 덮어써 흔적을 제로화함.

#### 한줄 요약

- 허락받고 $\to$ 열쇠 두 개 받아서 $\to$ 생 열쇠로 잠그고 $\to$ 포장된 열쇠랑 같이 저장한 뒤 $\to$ 생 열쇠는 부숴버린다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시크릿 매니저 (Secret Manager)**: 암호화 열쇠 말고, "DB 접속 비번"이나 "카톡 API 토큰" 같은 텍스트 쪼가리를 관리하고 정기적으로 갈아치워주는 전문 창고다.

</details>

| 키 관리 수단 | **HSM (물리적 금고)** | **KMS (중앙 사령부)** | **Secret Manager (비번 창고)** |
|:---|:---|:---|:---|
| 핵심 특징 | **부수면 돈 다 타버리는 현금 수송차** | **누가 언제 열쇠 썼는지 감시하는 경비실** | **포스트잇에 적던 비번 모아둔 특수 캐비닛** |
| 핵심 기술 원리 | 뜯어보는 순간 안에 있는 칩을 녹여버리는 **물리적 템퍼 저항성(Tamper Resistance)을 갖춤** | 클라우드 전역의 암호키 수명을 관리하고, **IAM 권한과 결합해 열쇠를 자동 회전(갱신)함** | DB 패스워드, OAuth 토큰 등 텍스트 기반의 **자격증명을 배포하고 주기적으로 회전함** |
| 적용(최고 장점) | 최상위 루트 키나 인증서 서명키 등 **절대 침해당하면 안 되는 1급 기밀을 보관함** | 전사적인 암호화 정책 통일, 권한 분리, 및 감사 로그(Audit) 추적을 **한 번에 해결함** | 소스코드에 하드코딩된 **취약한 평문 패스워드들을 싹 다 박멸함** |
| 치명적 한계 | 물리 장비라 가격이 미치게 비싸고 **클라우드 확장이 엄청 뻣뻣함** | KMS 중앙 서버가 뻗어버리면 **전사 데이터 복호화가 불가능해지는 대마비가 옴** | 대용량 DB 데이터를 '직접' 암호화하기엔 속도와 구조가 **전혀 맞지 않음** |

#### 한줄 요약

- 무식하게 단단한 금고는 'HSM', 똑똑한 열쇠 배급소는 'KMS', 접속 비번용 금고는 '시크릿 매니저'다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **이중 통제 (Dual Control)**: 은행 금고 열 때처럼, 관리자 2명이 각자 다른 열쇠를 동시에 돌려야만 최고 마스터키를 뽑을 수 있는 룰이다.
- **분할 지식 (Split Knowledge)**: 열쇠를 반으로 쪼개서, A관리자는 앞부분만 알고 B관리자는 뒷부분만 알게 해서 한 놈이 배신해도 못 털게 만드는 거다.
- **제로화 (Zeroization)**: 열쇠를 다 썼으면 그냥 지우는 게 아니라, 그 자리에 0이나 쓰레기값을 수십 번 덮어써서 포렌식해도 절대 복구 못하게 박멸하는 거다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 해커가 서버실 침투해서 **암호 금고(HSM)를 도끼로 찍어 분해함** | 물리적 장비 내부 메모리 칩셋을 직접 추출(Dump)하려는 사이드 채널 공격 시도 | **FIPS 140-3(Level 3 이상) 인증 HSM** 물리적 템퍼 감지 및 **자동 제로화 폭파 강제** | 물리적 침탈(Tampering) 발생 시 즉각 키 파기 및 하드웨어 추출 원천 차단 |
| 빡친 내부 관리자가 **최고 루트 키 들고 퇴사 후 외부 유출함** | 단일 최고 관리자 1명에게 루트 키 생성/복구 등 막강한 통제 권한이 집중됨 | 최고 권한 행사 시 2명 이상이 동의해야 하는 **이중 통제 및 분할 지식 강제 적용** | 내부자(Insider) 단독 배신 방어 및 권한 오남용을 통한 마스터키 탈취 방지 |
| 연산 다 끝난 **램(RAM) 잔해(Dump) 뜯어서 생 열쇠(DEK) 복구함** | 평문 DEK를 사용하고 난 뒤, 메모리 공간을 즉시 초기화하지 않고 쓰레기값으로 방치함 | 메모리 변수 사용 직후 해당 RAM 주소를 무작위 비트로 **즉각 완전 제로화(Zeroization)** | 메모리 포렌식(Cold Boot) 및 덤프를 통한 잔재 암호키 추출(소급 해독) 완벽 차단 |

#### 한줄 요약

- 부수면 발생하게 만들고, 관리자 두 명이 키 쪼개서 갖게 하고, 램에서 쓴 열쇠는 쓰레기값 부어서 박멸해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 데이터 보호의 근간을 지키기 위해 최상위 키는 **HSM** 대상 , 수명주기는 **KMS** 대상 맡기는 계층화(봉투 암호화)를 설계하고, **이중 통제** 및 **제로화** 활용 강제하여 내부자 배신과 메모리 잔존 유출을 절대 불허하는 기조를 확립함

#### 한줄 요약

- 암호화의 시작과 끝이다. 키를 침해당하면 데이터는 평문과 다름없다. 금고와 장부를 확실히 잠가라.
