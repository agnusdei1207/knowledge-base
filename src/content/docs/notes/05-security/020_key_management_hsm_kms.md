## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **KMS (Key Management System)**: 암호키의 생성, 배포, 저장, 회전, 폐기 전 생애주기를 중앙 집중식으로 통제하는 보안 플랫폼.
- **HSM (Hardware Security Module)**: 마스터키를 외부로 반출하지 않고 칩 내부에서만 연산하며 물리적 침해 시 자폭 소거하는 전용 보안 하드웨어.

</details>

- 정의/개념: **HSM·KMS**로 키 생애주기와 엔벨로프 암호화를 통제하는 기술
- 배경/필요성: 애플리케이션 코드나 설정 파일에 암호키를 하드코딩하여 보관하는 방식은 소스코드 유출 시 전사 기밀이 즉시 노출되는 치명적인 취약점을 가지며, 단일 마스터키로 수십 테라바이트의 대용량 데이터를 직접 암호화할 경우 키 회전(Key Rotation) 시마다 전체 데이터베이스를 재암호화해야 하는 막대한 연산 병목과 다운타임을 초래함에 따라, FIPS 140-3 하드웨어 보안 모듈(HSM)의 물리적 탬퍼 방지(Tamper-Resistance) 경계 내에서 마스터키(KEK)를 보호하고 데이터키(DEK)를 래핑(Wrapping)하는 2계층 봉투 암호화(Envelope Encryption) 및 중앙 집중형 키 관리 시스템(KMS)을 도입하여 **마스터키의 온칩(On-Chip) 격리 연산, 대용량 데이터의 로컬 고속 암호화 및 NIST SP 800-57 표준 기반 키 전 생애주기(생성/보관/회전/폐기) 통제**를 달성할 필요

#### 한줄 요약
- HSM 물리 격리와 KEK/DEK 엔벨로프 암호화를 통해 안전한 암호키 전 생애주기 거버넌스를 실현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Envelope Encryption (엔벨로프 암호화)**: 마스터키(KEK)로 데이터키(DEK)를 암호화하고, 데이터키(DEK)로 실제 대용량 데이터를 암호화하는 2계층 암호화 기법.
- **Zeroization (제로화)**: 메모리나 스토리지에 잔존하는 암호키를 0x00 또는 무작위 비트로 덮어써 흔적을 완전히 소거하는 FIPS 표준 파기 절차.

</details>

- 템퍼 감지 시 **제로화**로 HSM 내부 키 유출 차단
- **KEK·DEK 엔벨로프 암호화**로 대용량 로컬 처리
- **NIST SP 800-57**에 따른 생성·회전·폐기 통제

#### 한줄 요약
- 대용량 데이터를 HSM 안으로 넣지 않으려고 평문 DEK를 애플리케이션 메모리로 내보내는 구조이므로, 처리량을 얻은 대가는 그 메모리 잔존 구간을 제로화로 스스로 막아야 한다는 책임이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **KEK (Key Encryption Key)**: HSM 경계 밖으로 절대 나가지 않은 채 DEK만 래핑·언래핑함으로써, 데이터 재암호화 없이 이 키 하나의 교체·파기만으로 하위 키 전체를 통제하는 상위 마스터키.
- **DEK (Data Encryption Key)**: 실제 데이터를 덮는 대칭키로, KEK로 래핑된 상태로 암호문 옆에 함께 보관되고 사용 시점에만 평문으로 풀려 대용량 처리를 HSM 밖에서 감당하는 하위 키.

</details>

```text
[엔벨로프 암호화 및 KMS/HSM 상호작용 아키텍처]
|-- Application (1. KMS로 GenerateDataKey API 요청 전송)
`-- KMS / FIPS 140-3 Level 3 HSM
    |-- KEK (Key Encryption Key: HSM 내부 영구 격리)
    |-- TRNG (하드웨어 난수 발생기로 평문 DEK 생성)
    `-- KEK로 DEK 암호화 -> [ 래핑된 DEK (Ciphertext DEK) ]
`-- App Memory Execution (2. 평문 DEK로 DB 데이터 암호화 -> 3. 암호문+래핑된 DEK 저장 -> 4. 메모리 제로화 0x00)
```

선의 의미: KMS/HSM이 평문 DEK와 KEK로 암호화된 DEK를 발급하고 앱이 데이터 암호화 후 래핑된 DEK와 함께 저장하며 평문 DEK는 메모리에서 즉시 제로화하는 구조

| 구성요소 | 책임 |
|:---|:---|
| HSM | KEK 생성·보관과 **템퍼 감지 제로화** |
| KMS | 접근 정책·감사·**키 회전** 일정 통제 |
| KEK | HSM 내부에서 **DEK 래핑** 수행 |
| DEK | 대용량 데이터의 **대칭키 암호화** 수행 |
| 키 메타데이터 저장소 | 키 상태·만료일·**버전** 관리 |

#### 한줄 요약
- HSM은 KEK 연산만 떠안고 대용량 데이터 암호화는 애플리케이션에 남겨 두므로, 고가의 물리 보안 장비를 처리량 병목으로 만들지 않으면서도 신뢰의 뿌리는 칩 안 한 곳으로 좁힌다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **NIST SP 800-57 5단계 생애주기**: 1. 생성(Pre-Activation) → 2. 활성화(Active) → 3. 회전/비활성화(Deactivated) → 4. 무효화(Compromised) → 5. 암호학적 파기(Destroyed).

</details>

```text
GenerateDataKey 요청, HSM DEK 생성, 로컬 암호화 및 메모리 제로화 파이프라인
        │
      [데이터키 요청] 애플리케이션이 KMS에 DEK 요청
        │
   1. [인가·DEK 생성] IAM 검증 후 HSM에서 DEK 생성
        │
   2. [DEK 래핑] KEK로 DEK를 암호화
        │
   3. [로컬 암호화] 평문 DEK로 데이터를 암호화해 저장
        │
   ▼
   4. [메모리 제로화] 평문 DEK 버퍼를 즉시 소거
        │
      [완료 응답] 암호문과 래핑된 DEK 보관
```

- 1. 인가·DEK 생성: 정책을 통과한 요청에 임의의 데이터키 발급
- 2. DEK 래핑: HSM 내부 KEK로 데이터키를 암호화
- 3. 로컬 암호화: 평문 데이터키로 애플리케이션 데이터를 암호화
- 4. 메모리 제로화: 사용을 마친 평문 데이터키의 잔존 방지

#### 한줄 요약
- KMS 왕복은 DEK 발급 1회로 끝나고 이후 데이터 암호화는 전부 로컬에서 처리되므로, 평문 DEK가 메모리에 살아 있는 구간이 곧 이 설계가 성능을 얻는 대가이자 제로화로 최소화해야 할 노출 창이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **전용 HSM (Dedicated HSM)**: 키를 칩 밖으로 반출하지 않고 서명·래핑 연산까지 장비 안에서 끝내 최상위 키의 물리적 침해 경로를 없애고, 그 대가로 장비 단위 증설이라는 확장 한계를 갖는 형태.
- **클라우드 KMS (Cloud KMS)**: 멀티 테넌트 HSM을 API 뒤에 숨겨 두고 DEK 발급·복호화만 노출함으로써, 개별 조직이 장비를 운영하던 비용을 호출 단위 과금으로 대체하는 관리형 형태.
- **시크릿 매니저 (Secret Manager)**: 암호키가 아니라 DB 계정·API 토큰 같은 평문 비밀값을 보관·회전·동적 발급해, 애플리케이션 설정 파일에 흩어져 있던 자격증명을 조회 시점 주입으로 옮기는 형태.

</details>

| 비교 항목 | 전용 하드웨어 HSM (Dedicated HSM) | 클라우드 관리형 KMS (AWS/Azure KMS) | 시크릿 매니저 (HashiCorp Vault / SM) |
|:---|:---|:---|:---|
| **주요 보호 대상** | **최상위 Root CA 키, KEK, PKI 서명키** | **클라우드 스토리지(EBS/S3/DB) 암호키** | **DB 접속 ID/PW, API 토큰, TLS 인증서** |
| **물리적 보안 인증** | **FIPS 140-3 Level 3 / Level 4** | FIPS 140-3 Level 3 멀티 테넌트 HSM | 소프트웨어 기반 (백엔드 KMS 연동) |
| **주요 암호 연산** | **HSM 내부 암호 연산 (On-Chip Crypto)**| **엔벨로프 암호화 (DEK 발급/복호화)** | **평문 비밀값 조회 및 동적 자격증명 발급** |
| **확장성 및 유연성** | 물리 장비로 확장 한계, 고비용 | **클라우드 네이티브 오토스케일링** | **멀티 클라우드 API 오케스트레이션** |
| **주요 적용 영역** | **금융 결제망, 공인 인증기관, 국가 기밀** | **클라우드 엔터프라이즈 데이터 암호화**| **CI/CD 파이프라인, 마이크로서비스 앱** |

#### 한줄 요약
- HSM은 최상위 키 물리적 금고, KMS는 대용량 엔벨로프 암호화 허브, 시크릿 매니저는 계정 토큰 관리소이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Crypto-Shredding (암호학적 파기)**: 대규모 분산 스토리지 내 데이터를 물리 삭제하지 않고 해당 KEK/DEK를 KMS에서 영구 파기하여 데이터를 복구 불가능하게 만드는 기술.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 단일 관리자 계정 탈취로 인한 **최상위 KEK 마스터키 임의 삭제 및 데이터 영구 손실** | **`이중 통제(M-of-N Quorum), 삭제 유예 기간(7~30일)` 및 루트 키 분할** | 단독 파기 사고 방지 및 침해 시 유예 기간 내 복원 보장 |
| 서버 크래시 시 코어 덤프 파일에 **평문 DEK가 잔존하여 유출되는 사고** | **연산 직후 `명시적 메모리 제로화(Zeroization)` 및 `Non-Dumpable 메모리 락(mlock)`** | 메모리 덤프 분석을 통한 잔재 암호키 추출 100% 차단 |
| 수억 건의 사용자 탈퇴 시 백업 데이터 내 개인정보 물리 삭제 불능 | **사용자별 독립 KEK/DEK 매핑 기반 `크립토 슈레딩(Crypto-Shredding)`** 적용 | 키 파기만으로 백업 내 데이터 영구 복구 불가 달성 |
| KMS 장애 시 전사 대용량 데이터 암복호화 일괄 중단 위험 | **`다중 리전 KMS 복제(Multi-Region Key)` 및 로컬 DEK 캐싱 정책** 수립 | KMS 가용성 99.999% 확보 및 비즈니스 연속성 유지 |

#### 한줄 요약
- 이중 통제로 키 삭제를 방지하고, mlock/제로화로 메모리를 보호하며, 크립토 슈레딩으로 영구 삭제를 구현한다.

## Ⅶ. 결론

- 암호화 시스템의 실질적 안전성을 좌우하는 암호키의 전 생애주기를 체계적으로 통제하고 물리적/논리적 도난을 원천 차단하는 **현대 엔터프라이즈 정보보안, 클라우드 거버넌스 및 금융 컴플라이언스의 가장 필수적인 신뢰 기반 기술(FIPS 140-3 및 NIST SP 800-57 표준)**로 확고히 정립되었으며, 포스트 양자암호(PQC) 키 관리 및 기밀 컴퓨팅 KMS 통합으로 진화하는 가운데, 실무 키 관리 아키텍처 구축 시에는 **최상위 Root CA 및 KEK를 물리적으로 완벽히 격리하는 FIPS 140-3 Level 3 HSM 기반 온칩 암호 연산, 대용량 스토리지 재암호화 오버헤드를 제거하는 KEK/DEK 2계층 봉투 암호화(Envelope Encryption) 표준화, 관리자 계정 탈취에 의한 고의적 키 삭제를 방어하는 M-of-N 다중 쿼럼(Quorum) 승인 및 삭제 유예 기간(Soft-Delete) 정책**을 결합하여 완벽한 키 거버넌스 신뢰성을 완성

#### 한줄 요약
- 키 관리는 HSM 물리 격리와 KEK/DEK 엔벨로프 구조 및 생애주기 통제를 결합하여 안전한 키 거버넌스를 실현하는 핵심 보안 인프라다.
