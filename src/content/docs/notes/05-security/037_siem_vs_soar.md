## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM(Security Information and Event Management)**: 전사 이종 보안 장비 및 시스템 로그를 중앙 집중 수집·정규화하여 실시간 시계열 상관분석(Correlation)을 통해 위협 경보(Alert)를 생성하고 가시성을 제공하는 탐지 플랫폼.
- **SOAR(Security Orchestration, Automation, and Response)**: SIEM 등에서 인입된 보안 경보를 트리거로 삼아, 사전 정의된 플레이북(Playbook)에 따라 CTI 평판 조회, 티켓 생성, 방화벽/EDR/IAM 차단 API를 오케스트레이션하여 능동 대응을 자동화하는 플랫폼.

</details>

- 정의/개념: 탐지 중심의 데이터 허브인 **SIEM** 과 실행 중심의 대응 오케스트레이터인 **SOAR** 를 **공통 사건 상관 식별자(Incident Correlation ID)** 및 **폐쇄 루프 환류(Closed-Loop Feedback)** 로 결합한 **현대 차세대 SOC 탐지-대응 통합 아키텍처**
- 배경/필요성: SIEM 도입으로 위협 탐지 역량은 향상되었으나 수동 대응 체계의 인력 한계로 인해 발생하는 탐지-대응 간 병목 현상(MTTD는 단축되었으나 MTTR은 지연)을 해소할 요구

#### 한줄 요약
- SIEM의 실시간 상관분석 탐지와 SOAR의 플레이북 기반 자동 대응을 결합하여 탐지부터 복구까지의 폐쇄 루프를 완성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **인계 계약(Handoff Contract / Interface Specification)**: SIEM에서 생성된 보안 인시던트 데이터(사건 ID, 위험 점수, 출발지/목적지 IP, 관련 원시 로그 증적)가 손실 없이 SOAR로 전달될 수 있도록 규정한 표준화된 API 데이터 교환 규격.
- **폐쇄 루프 환류(Closed-Loop Feedback)**: SOAR의 플레이북 실행 결과(실제 침해 여부, 오탐 판정, 차단 성공 증적)를 다시 SIEM의 상관분석 룰 엔진으로 환류하여 탐지 룰셋을 능동 튜닝하는 선순환 구조.

</details>

- **명확한 기능적 분업**: SIEM은 대규모 빅데이터 상관분석 및 위협 탐지(Detection), SOAR는 이종 API 지휘 및 무인 대응(Response)
- **공통 사건 ID 기반 트랜잭션 추적**: 단일 침해사고에 대해 탐지 로그(SIEM)와 대응 실행 이력(SOAR)을 1:1로 결합 추적
- **탐지 공학-대응 자동화 상호 고도화**: SOAR의 Triage 결과를 바탕으로 SIEM의 오탐 룰을 지속적으로 리팩토링

#### 한줄 요약
- 탐지-대응 기능 분업, 공통 사건 ID 기반 엔드투엔드 추적, 폐쇄 루프 환류를 통한 탐지 룰 지속 최적화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **양방향 오케스트레이션 파이프라인**: SIEM은 인바운드 텔레메트리 수집 및 분석에 집중하고, SOAR는 아웃바운드 REST API 호출을 통해 EDR 격리, 방화벽 ACL 추가, Active Directory 계정 잠금을 집행하는 협업 구조.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 전사 IT 및 보안 인프라 (Firewall, EDR, Server, Cloud, Network) ]     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (1. 대규모 원시 로그 스트리밍)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. SIEM 플랫폼 (Detection Engine: 탐지 레이더) ]                      │
│  ├─ 로그 정규화 (CEF/ECS) ➔ 다차원 시계열 상관분석                      │
│  └─ [ 고위험 침해 인시던트 생성: Alert ID #1024 (위험도: High) ]        │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (2. Handoff Contract: REST API / Webhook)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. SOAR 플랫폼 (Response Engine: 대응 오케스트레이터) ]                │
│  ├─ CTI 평판 자동 보강 (VirusTotal / MISP)                              │
│  ├─ 워크플로 실행: [ OASIS CACAO 2.0 표준 플레이북 ]                    │
│  └─ 승인 분기: Human-in-the-loop (Slack 승인 포털)                      │
└──────────────────┬──────────────────────────────────┬───────────────────┘
                   │ (3. 다중 API 제어 명령)          │ (4. Closed-Loop 결과 환류)
                   ▼                                  ▼
┌──────────────────────────────────────┐┌──────────────────────────────────────┐
│ [ 실행 계층 (Action Executors) ]     ││ [ SIEM 상관분석 룰 튜닝 피드백 ]     │
│  ├─ NGFW: C2 IP 블랙리스트 등록      ││  ├─ 실제 침해 증적 저장 (WORM)       │
│  ├─ EDR: 감염 호스트 네트워크 격리   ││  └─ 오탐 피드백 ➔ 룰 임계치 자동 조정│
│  └─ AD: 사용자 계정 비활성화         ││                                      │
└──────────────────────────────────────┘└──────────────────────────────────────┘
```

선의 의미: SIEM이 이종 로그를 분석하여 인시던트를 생성하면, SOAR가 플레이북을 가동해 장비들을 자동 제어하고 그 결과를 SIEM에 환류하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **SIEM 탐지 엔진** | 이종 대용량 로그 수집, 표준 스키마 정규화, 다차원 상관분석 및 경보 생성 | Detection Core |
| **인계 인터페이스 (Handoff)**| SIEM 알람을 SOAR로 무손실 전달하기 위한 표준 JSON/REST API 스키마 | API Contract |
| **SOAR 플레이북 엔진** | 위협 Triage, CTI 맥락 보강, 승인 분기, 이종 API 차단 명령 오케스트레이션 | Response Core |
| **타격 실행 커넥터** | 방화벽, EDR, Active Directory, WAF와 연동되어 실제 격리/차단 명령 집행 | Action Connectors |
| **폐쇄 루프 환류 모듈** | SOAR 조치 결과 및 오탐 여부를 SIEM 룰셋으로 피드백하여 탐지 정밀도 개선 | Feedback Loop |

#### 한줄 요약
- SIEM 탐지 엔진, 인계 인터페이스, SOAR 플레이북 엔진, 타격 실행 커넥터, 폐쇄 루프 환류 모듈이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SIEM-SOAR 연동 5단계 라이프사이클**:
  1. **탐지(Detect)**: SIEM 시계열 상관분석으로 이상 징후 포착
  2. **인계(Handoff)**: 사건 ID와 원본 증적을 SOAR로 전송
  3. **보강 및 승인(Enrich & Approve)**: CTI 조회 및 Human-in-the-loop 검증
  4. **격리 및 집행(Execute)**: EDR/방화벽 API 호출로 차단
  5. **환류(Feedback)**: 조치 결과 증적을 SIEM에 보존하고 룰 최적화

</details>

```text
1. [SIEM 탐지] 방화벽 및 EDR 로그 상관분석 ➔ "비인가 권한 상승 후 C2 통신 발생" 인시던트 식별
            │
            ▼
2. [표준 인계] SIEM이 사건 ID(#1024), 대상 호스트 IP, 사용자 계정, 로그 증적을 JSON으로 SOAR에 전달
            │
            ▼
3. [SOAR 보강 및 판정] CTI TIP 플랫폼과 연동하여 대상 C2 IP 평판 자동 조회 ➔ [위험도 Critical 확정]
            │
            ▼
4. [오케스트레이션 차단] 플레이북에 따라 EDR API(호스트 격리) 및 NGFW API(C2 차단) 동시 호출
            │
            ▼
5. [상태 검증 및 폐쇄 루프] EDR/방화벽의 정책 적용 증적을 수집하여 ITSM 티켓 종결 및 SIEM 룰 튜닝 반영
```

**동작 원리**

1. **상관 패턴 인지**: 다기종 장비의 단편적 이벤트를 연결하여 APT 공격 흐름 도출
2. **트랜잭션 인계**: JSON-RPC/REST 호출을 통해 분석에 필요한 메타데이터를 SOAR로 전달
3. **무인 텔레메트리 심사**: 위협 인텔리전스 점수를 바탕으로 사전 정의된 임계치 초과 여부 확인
4. **동시 다발적 차단 집행**: 단일 인시던트에 대해 네트워크와 엔드포인트를 병렬로 즉각 격리
5. **학습형 선순환 유지**: 대응 성공/실패 이력을 데이터베이스에 누적하여 차기 관제 룰셋 개선

#### 한줄 요약
- SIEM 상관 탐지, 표준 JSON 인계, SOAR CTI 보강, EDR/방화벽 동시 차단, 폐쇄 루프 환류 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SIEM vs SOAR 핵심 기능 비교**: 목적, 데이터 방향성, 주요 동작, 도입 효과의 비교.

</details>

| 비교 항목 | 보안 정보 및 이벤트 관리 (SIEM) | 보안 오케스트레이션 및 대응 (SOAR) |
|:---|:---|:---|
| **핵심 목적** | **전사 위협 가시성 확보 및 실시간 상관 탐지** | **침해사고 조사 및 대응 조치 무인 자동화** |
| **주요 역할 비유** | **보안 관제 센터의 '눈과 귀' (탐지 레이더)** | **보안 관제 센터의 '손과 발' (자동 대응 타격대)** |
| **데이터 흐름 방향** | **인바운드 중심 (이종 시스템 로그 대량 수집)**| **양방향 (경보 수신 후 이종 장비로 제어 API 송출)**|
| **핵심 기술 컴포넌트** | **파서, 공통 스키마(CEF/ECS), 상관분석 룰** | **플레이북(CACAO), API 커넥터, 상태 머신** |
| **주요 단독 운용 한계**| 수동 대응 병목으로 인한 MTTR 지연 (알람 피로도)| 탐지 트리거 및 원본 빅데이터 증적 부재 |
| **핵심 도입 효과** | **미탐 방지 및 침해 시나리오 실시간 가시화** | **MTTR 90% 이상 단축 및 관제 수작업 오버헤드 제거**|

#### 한줄 요약
- SIEM은 대규모 로그 상관 탐지(눈), SOAR는 이종 장비 API 오케스트레이션 대응(손발)을 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **SIEM-SOAR 통합 아키텍처 거버넌스**:
  - NIST SP 800-92: 로그 수집 무결성 및 장기 보존 표준
  - OASIS CACAO 2.0: 플레이북 상호운용성 표준

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SIEM 경보 형식이 비표준화되어 **SOAR 플레이북 파싱 실패 및 자동 대응 파이프라인 단절** | **CEF/ECS 기반 표준 인계 계약(Handoff Contract) 수립 및 JSON Schema 검증** | 탐지-대응 간 데이터 인계 성공률 100% 달성 및 파싱 에러 방지 |
| SOAR 조치 결과(차단 완료/오탐 판정)가 **SIEM으로 환류되지 않아 동일 오탐 경보가 반복 발생** | **사건 ID 기반의 양방향 폐쇄 루프(Closed-Loop) 환류 파이프라인 의무화** | 오탐 룰의 능동적 자동 튜닝 및 관제 요원 알람 피로도 80% 이상 해소 |
| 이종 벤더 보안 장비 교체 시 **기존 SOAR 플레이북과 SIEM 탐지 룰을 전면 재개발하는 락인** | **OASIS CACAO 2.0 표준 플레이북 스펙 및 Sigma 공통 탐지 룰 표준 채택** | 벤더 종속성 완전 탈피 및 인프라 변경 시 플레이북 100% 재사용성 보장 |

#### 한줄 요약
- 표준 인계 계약으로 파이프라인을 유지하고, 폐쇄 루프로 오탐을 튜닝하며, CACAO/Sigma로 벤더 락인을 제거한다.

## Ⅶ. 결론

- 지능형 사이버 위협에 대응하여 관제 센터의 완결성을 확보하는 **SIEM과 SOAR의 결합 아키텍처**는 현대 SOC 운영의 핵심 표준이며, 실무 구현 시 **CEF/ECS 기반의 무손실 인계 계약(Handoff Contract) 체결**, **OASIS CACAO 기반 표준 플레이북 구축**, **사건 ID 기반의 양방향 폐쇄 루프(Closed-Loop) 환류 체계**를 통합 가동하여 탐지(MTTD)와 대응(MTTR)을 초 단위로 통합하는 차세대 보안 운영 환경을 완성

#### 한줄 요약
- SIEM의 상관분석 탐지와 SOAR의 플레이북 오케스트레이션을 폐쇄 루프로 결합하여 무결점 자동 대응을 실현한다.
