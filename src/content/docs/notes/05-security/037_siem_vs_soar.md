## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **SIEM (보안 정보 및 이벤트 관리)**: 회사 내 모든 로그를 긁어모아 "어? 이거 해킹이네!" 하고 알람을 울려주는 거대한 중앙 상황판(탐지 레이더)이다.
- **SOAR (보안 오케스트레이션·자동화 및 대응)**: SIEM 알람을 받아서, 미리 짜놓은 각본(플레이북)대로 알아서 타 장비들을 지휘해 차단 버튼까지 눌러주는 자동화 로봇(대응 타격대)이다.

</details>

- 정의: 탐지 전문 데이터 허브(SIEM)와 자동화 대응 로봇(SOAR)을 연계한 현대 보안관제 핵심 구조다.
- 배경: SIEM이 아무리 똑똑하게 알람을 띄워줘도, 사람이 손으로 일일이 쳐내다가는 탐지-조치 병목 현상에 걸려 골든타임을 다 날리고 침해당하기 때문이다.

#### 한줄 요약

- CCTV 상황판(SIEM)이 도둑을 발견하면, 터미네이터 로봇(SOAR)이 출동해서 알아서 때려잡는 콤비 시스템이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **사건 ID (Incident Correlation ID)**: "SIEM에서 울린 알람 #123번"과 "SOAR에서 차단 중인 작업 #123번"이 같은 사고라고 연결해 주는 꼬리표다.
- **폐쇄 루프 (Closed-loop Feedback)**: SOAR가 차단해 보니 "이거 정상 유저 오탐이네"라는 결과를 다시 SIEM한테 알려줘서, 다음엔 안 울리게 SIEM 룰을 고치는 순환 체계다.

</details>

- **역할 분담**: SIEM은 이종 로그를 긁어모아 상관분석으로 경보를 띄우고, SOAR는 그걸 받아 플레이북대로 자동 조치한다.
- **연결 고리**: 두 시스템이 단절되지 않게, 공통 사건 ID(Incident Correlation ID)를 써서 탐지 알람과 조치 티켓을 묶는다.
- **폐쇄 루프 환류**: 차단이나 오탐 결과를 SIEM 탐지 룰(Rule)에 다시 반영(Feedback)하여, 서로의 정밀도를 끌어올린다.

#### 한줄 요약

- 역할 나누고, 사건 번호(ID)로 묶고, 처리 결과는 피드백 줘서 서로 진화하는 방어 체계다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **인계 계약 (Handoff Contract)**: SIEM이 SOAR한테 "알람 던질 테니 받아라" 할 때, IP 주소, 타임스탬프, 로그 증거를 어떤 포맷으로 줄지 사전에 맞춰 놓은 규격(API 인터페이스)이다.
- **EDR / IdP**: SOAR 로봇이 차단 명령을 내릴 때, PC 랜선을 물리적으로 뽑는 건 EDR(단말)한테 시키고, 클라우드 계정을 잠그는 건 IdP(인증 시스템)한테 시킨다.

</details>

```text
[ SIEM / SOAR 연계 아키텍처 ]

[ 1. SIEM 수집 및 상관 탐지 ] ── ("새벽에 사장님 계정으로 이상한 접속 떴다!" 알람)
      │
      ▼
[ 2. 인계 계약 (인터페이스) ] ── ("사건 알람 번호 #123, IP, 로그 원본을 규격에 맞춰 던짐")
      │
      ▼
[ 3. SOAR 보강 및 자동 조치 ] ── ("사장님 폰으로 2차 인증 확인하고, 안 맞으면 바로 컷!")
      │
      ▼
[ 4. EDR / IdP (실제 타격망) ] ── (SOAR 명령받고 EDR이 PC 랜선 뽑고, IdP가 계정 잠금)
      │
      ▼
[ 5. 폐쇄 루프 결과 환류 ] ── ("차단 완료했음. 찐 해커 맞으니까 SIEM 탐지 룰 유지해")
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **SIEM 탐지 및 상관** | 원본 로그를 모아 상관분석하고 **최초의 해킹 알람과 증거를 생성함** | Detect |
| **인계 계약 (Handoff)** | SIEM 알람을 SOAR 로봇이 씹어먹을 수 있게 **데이터 포맷 규격을 맞춤** | API |
| **SOAR 보강 및 조치** | 알람을 받아 위협 정보를 더 캐보고 **플레이북대로 차단 승인을 진행함** | Respond |
| **EDR / IdP 타격망** | SOAR의 지시를 받아 **실제로 감염 PC를 격리(EDR)하고 계정을 잠금(IdP)** | Execute |
| **폐쇄 루프 환류** | 뻘짓 조치(오탐) 결과를 SIEM에 **다시 피드백 줘서 다음 탐지 룰을 교정함** | Feedback |

#### 한줄 요약

- SIEM이 찾고 $\to$ 규격 맞춰 던져주면 $\to$ SOAR가 로직 굴려서 $\to$ EDR/IdP로 타격하고 $\to$ 결과를 피드백한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ SIEM 탐지부터 SOAR 자동 조치까지의 흐름 ]

┌──────────────────────────────┐
│ 1. [SIEM: 상관분석 및 위험도 산정]
│ ("로그 엮어보니 이거 빨간 맛 해킹 맞네. SOAR한테 사건 ID 넘겨!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [SOAR: 현재 상태 보강 (Enrichment)]
│ ("넘겨받은 IP, 위협 인텔리전스(CTI)에서 한 번 더 뒤져. 라자루스네?")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [SOAR: 승인 및 정책 분기 (Human-in-the-loop)]
│ ("이건 너무 큰 사고니까, 기계가 막지 말고 일단 사장님한테 승인받아!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [EDR/IdP: 격리, 차단 및 실행]
│ ("승인 떨어짐! 당장 최소 권한 API로 EDR 쏴서 PC 네트워크 랜선 뽑아!")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 5. [폐쇄 루프: 실행 증적 수집 및 SIEM 환류]
│ ("랜선 뽑힌 거 재확인했음. 이 차단 완료 증거 SIEM한테 다시 보내줘!")
└──────────────────────────────┘
```

### 동작 원리

1. SIEM 탐지/인계: 원본 로그 상관분석으로 경보를 생성하고, 인계 계약에 따라 사건 ID를 SOAR에 전달함.
2. SOAR 맥락 보강: 수신된 경보에 타깃 대상 장비 상태와 위협 인텔리전스(CTI) 정보를 결합함.
3. 승인 분기: 비즈니스 영향도를 판단하여 자동/수동/사람 승인(Human-in-the-loop) 실행 모드를 결정함.
4. 조치 실행: 승인된 플레이북을 통해 EDR, IdP 등 외부 통제 장비에 격리 API 명령을 호출함.
5. 검증 및 폐쇄 루프: 실제 정책 변경 증적을 확인하고, 오탐/차단 결과를 SIEM 상관 룰에 환류함.

#### 한줄 요약

- 레이더에 잡히면 $\to$ 한 번 더 검증하고 $\to$ 승인받아서 $\to$ 총 쏘고 $\to$ 명중했는지 SIEM에 보고한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **탐지 근거 (SIEM)**: SIEM이 갖고 있는 원본 방화벽 로그 같은 빼박 해킹 증거다.
- **대응 수행 (SOAR)**: SOAR가 랜선 뽑고 계정 잠그는 실제 차단 타격 행위다.

</details>

| 시스템 구분 | **SIEM (탐지 레이더 상황판)** | **SOAR (자동 대응 타격 로봇)** |
|:---|:---|:---|
| 핵심 특징 | **사각지대 없이 24시간 째려보는 CCTV 상황판** | **CCTV 보고 달려가서 범인 때려잡는 터미네이터** |
| 핵심 역할 및 책임 | 빅데이터 로그 상관분석, **탐지 근거 생성 및 경보 알람 발생** | 알람 수신 후 플레이북 기반 조사, **장비 지휘(Orchestration) 및 타격** |
| 주요 연동 방식 | 각종 방화벽, 서버, 백신에서 **일방적으로 로그를 수집받음** | CTI 위협 정보 조회 및 **차단 API 명령(Action)을 양방향 전송함** |
| 독립 운영 시 한계 | 알람만 겁나 울리고 조치를 안 해서 **대응 지연으로 해커한테 다 뚫림** | 트리거(알람)나 원본 로그 증거가 없어서 **허공에 무지성 주먹질만 함** |

#### 한줄 요약

- SIEM 없는 SOAR는 맹인이고, SOAR 없는 SIEM은 사지 마비다. 두 개를 붙여야 실전에서 돌아간다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-92**: 로그 수집(SIEM)을 훼손 없이 똑바로 하라는 미국 정부의 가이드라인이다.
- **OASIS CACAO 2.0**: 플레이북(SOAR) 짤 때 벤더 맘대로 하지 말고 이 국제 양식에 맞춰 통일하라는 표준이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| SIEM 알람을 SOAR가 **뭔 소린지 파싱(해석)을 못 해 뻗음** | SIEM이 넘겨주는 로그 포맷과 SOAR가 읽는 포맷(인계 계약)이 안 맞음 | **NIST SP 800-92** 및 SIEM/SOAR 간 **표준 인계 계약(인터페이스) 정의** | 탐지부터 자동 조치로 넘어가는 파이프라인의 데이터 무결성 100% 확보 |
| SOAR가 엉뚱한 서버 차단했는데 **SIEM은 그 서버 계속 모니터링함** | SOAR의 조치 결과(오탐/차단)를 SIEM한테 다시 알려주는 피드백 구조가 없음 | 공통 **사건 ID** 매핑 및 시스템 간 양방향 **폐쇄 루프(Closed-loop) 환류 강제** | 대규모 오조치 확산 방지 및 SIEM 상관분석 룰(Rule)의 자동 튜닝 |
| 보안 벤더 장비 바꾸니까 **기존 플레이북을 다 새로 다시 짜야 함** | 특정 보안 벤더의 플레이북 포맷에 락인(Lock-in)되어 이식성이 전혀 없음 | 플레이북 연동 **OASIS CACAO 2.0** 등 글로벌 표준 API 규격 절대 적용 | 특정 벤더 종속성 탈피 및 이기종 장비(EDR, IdP) 간 상호운용성 보장 |

#### 한줄 요약

- 규격 안 맞으면 인계 계약 맞추고, SOAR가 뻘짓하면 폐쇄 루프로 SIEM에 보고하며, 벤더 종속성은 표준(CACAO)으로 깨라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **운영 추적성 (Operational Traceability)**: 해킹 접수부터 $\to$ 승인 $\to$ 차단 $\to$ 보고까지, 과정이 끊기지 않고 로그 하나로 쭉 이어지는 방어 증명력이다.

</details>

- 관제 **운영 추적성** 확보를 위해 상관 탐지와 증거 관리는 **SIEM** , 플레이북 기반 자동 타격은 **SOAR** 분담하되, 공통 **사건 ID** 및 **폐쇄 루프(Closed-loop)** 환류를 통해 빈틈없는 철저한 방어 생태계를 구축하는 실무 기조를 확립함

#### 한줄 요약

- 누가 털었고 언제 막았는지 처음부터 끝까지 증거(추적성)를 남기려면, SIEM과 SOAR를 사건 ID로 결합해라.
