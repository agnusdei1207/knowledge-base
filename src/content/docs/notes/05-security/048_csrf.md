## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **교차 사이트 요청 위조(Cross-Site Request Forgery, CSRF)**: 브라우저의 자동 인증을 악용해 의도하지 않은 상태 변경을 유발하는 공격이다.

</details>

- 정의/개념: **CSRF**는 자동 인증으로 비승인 상태 변경을 유발하는 웹 공격이다.
- 배경/필요성: 세션 인증만으로는 현재 사용자가 요청한 변경인지 확인할 수 없다.

#### 한줄 요약

- CSRF는 로그인 쿠키가 자동 전송되는 점을 악용하므로 서버가 요청 의도까지 검증해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **세션 쿠키**: 로그인 상태를 식별하며 브라우저가 대상 사이트 요청에 자동 첨부하는 쿠키이다.
- **CSRF 토큰**: 서버가 발급하고 상태 변경 요청에서 검증하는 예측 불가능한 요청 의도 확인값이다.
- **SameSite**: 교차 사이트 요청에 세션 쿠키를 자동 전송할 범위를 제한하는 쿠키 속성이다.

</details>

- 브라우저가 **세션 쿠키**를 자동 첨부하는 동작이 권한 대리에 악용된다.
- 상태 변경 경로에서 **CSRF 토큰**과 출처를 함께 검증한다.
- **SameSite**는 교차 사이트 쿠키 전송을 줄이는 보조 계층이다.

#### 한줄 요약

- 토큰•출처 검사•SameSite 쿠키를 함께 적용하면 위조 요청이 상태 변경까지 도달하기 어렵다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **Origin**: 요청을 생성한 출처의 스킴•호스트•포트를 전달하는 헤더이다.
- **Referer**: 요청을 보낸 이전 페이지의 주소를 전달하는 헤더이다.
- **하이퍼텍스트 전송 프로토콜(Hypertext Transfer Protocol, HTTP)**: 웹 요청과 응답의 형식•의미를 정의하는 프로토콜이다.
- **안전 메서드**: 조회 의미만 가지며 서버 상태를 변경하지 않아야 하는 GET•HEAD 등의 HTTP 메서드이다.

</details>

```text
CSRF 검증 구조
├─ 세션 쿠키: 자동 첨부 인증 상태
├─ 상태 변경 경로: 자금•계정 변경 처리
├─ CSRF 토큰: 요청 의도 검증값
├─ 출처 정책: Origin•Referer 검증
└─ 쿠키 정책: SameSite•안전 메서드 적용
```

| 구성요소 | 책임 |
|:---|:---|
| 세션 쿠키 | 자동 첨부되는 **세션 쿠키** 인증 상태 제공 |
| 상태 변경 경로 | 자금•계정의 변경 요청 처리 |
| CSRF 토큰 | **CSRF 토큰**으로 요청 의도 확인 |
| 출처 정책 | **Origin**•**Referer** 검증 |
| 쿠키 정책 | **HTTP**의 **SameSite**•**안전 메서드** 적용 |

#### 한줄 요약

- 공격자 페이지가 피해자의 인증 상태를 빌려 요청해도 서버 검증기가 정상 화면에서 발급한 증거가 없으면 거부한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **의도 검증**: 토큰 일치•허용 출처•고위험 재인증으로 현재 사용자가 요청한 변경인지 확인하는 절차이다.
- **위조 상태 변경 요청 생성**: 공격자 페이지가 피해자 권한으로 처리할 업무 요청을 구성하는 단계이다.
- **세션 쿠키 자동 첨부**: 브라우저가 대상 사이트의 인증 쿠키를 위조 요청에 포함하는 단계이다.
- **세션 인증 통과**: 서버가 자동 첨부된 쿠키를 유효한 피해자 로그인으로 판정하는 단계이다.
- **사용자 의도 검증 누락**: 서버가 토큰•출처•재인증 없이 인증된 요청을 수용하는 단계이다.
- **비승인 상태 변경 실행**: 서버가 피해자 의사와 다른 업무 변경을 처리하는 단계이다.

</details>

```text
위조 폼•링크
      |
      v
1. 위조 상태 변경 요청 생성
      |
      v
2. 세션 쿠키 자동 첨부
      |
      v
3. 세션 인증 통과
      |
      v
4. 사용자 의도 검증 누락
      |
      v
5. 비승인 상태 변경 실행
      |
      v
처리 결과
```

### 동작 원리

1. **위조 상태 변경 요청 생성**: 공격자 페이지가 송금•계정 변경 요청을 구성해 위조 상태 변경 요청 생성을 완료한다.
2. **세션 쿠키 자동 첨부**: 브라우저가 대상 사이트 인증정보를 포함하는 세션 쿠키 자동 첨부가 일어난다.
3. **세션 인증 통과**: 서버가 피해자의 유효한 로그인 상태를 확인해 세션 인증을 통과시킨다.
4. **사용자 의도 검증 누락**: 토큰•Origin•재인증 없이 요청을 수용해 사용자 의도 검증 누락이 발생한다.
5. **비승인 상태 변경 실행**: 피해자 권한으로 공격자 지정 동작을 수행해 비승인 상태 변경을 실행한다.

#### 한줄 요약

- 서버는 상태 변경 요청에서 **의도 검증**을 통과한 뒤에만 업무 처리를 수행한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **CSRF 방어 선택 기준**: 요청 자체의 의도는 토큰, 쿠키 자동 전송은 SameSite, 요청 발생 위치는 출처 헤더로 확인하는 판단 기준이다.

</details>

| CSRF 방어 유형 | CSRF 토큰 | SameSite 쿠키 | 출처 검증 |
|:---|:---|:---|:---|
| 적용 기준 | 의도 직접 검증 | 쿠키 전송 제한 | 요청 출처 판정 |
| 핵심 특징 | **CSRF 토큰**으로 의도 확인 | **SameSite**로 교차 쿠키 전송 제한 | **Origin**•**Referer** 확인 |
| 한계 | 토큰 노출•검증 누락 | 호환성•예외 설정 문제 | 헤더 부재•중계 처리 오류 |

#### 한줄 요약

- **CSRF 방어 선택 기준**에 따라 토큰은 요청 의도를 확인하고 SameSite와 출처 검증은 교차 요청을 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **MITRE CWE-352**: 요청 의도를 충분히 검증하지 않는 약점을 정의한 공통 약점 분류이다.
- **IETF RFC 9110**: GET•HEAD 같은 안전 메서드와 HTTP 요청 의미를 정의한 인터넷 표준 문서이다.
- **교차 사이트 스크립팅(Cross-Site Scripting, XSS)**: 비신뢰 데이터가 브라우저 스크립트로 실행되는 취약점이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 세션 인증만 확인하면 위조 요청도 상태 변경 | **MITRE CWE-352** 기준으로 의도 검증 | 비승인 상태 변경 차단 |
| GET•HEAD가 상태를 바꾸면 외부 링크로 요청 유발 | **IETF RFC 9110**의 안전 메서드 준수 | 조회 요청의 업무 부작용 방지 |
| XSS에 토큰이 노출되거나 검증이 누락되면 CSRF 방어 무력화 | **XSS** 제거•출처 검증과 SameSite•재인증 결합 | 위조 요청 성공 가능성 완화 |

#### 한줄 요약

- 은행 서버는 세션 쿠키만 믿지 않고 송금 폼의 예측 불가능한 CSRF 토큰을 검증해 다른 사이트가 사용자의 권한으로 송금하지 못하게 한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **CSRF 다층 통제 기준**: 모든 상태 변경에는 토큰과 출처 검증을 적용하고 고위험 업무에는 재인증을 추가하는 기준이다.
- **재인증**: 고위험 상태 변경 직전에 사용자의 인증 요소를 다시 확인하는 통제이다.

</details>

- **CSRF 다층 통제 기준**에 따라 모든 상태 변경은 **CSRF 토큰**•출처 검증, 고위험 요청은 **재인증**을 추가한다.

#### 한줄 요약

- CSRF 방어는 토큰•출처 검사•쿠키 정책과 XSS 제거를 함께 운영해야 한다.
