## 미리 알고가기

- **사이트 간 요청 위조(Cross-Site Request Forgery, CSRF)**: 로그인된 브라우저의 자동 인증 정보를 악용하여 사용자가 의도하지 않은 상태 변경 요청을 보내는 공격이다.
- **세션 쿠키**: 로그인 상태를 식별하며 브라우저가 대상 사이트 요청에 자동 첨부하는 값
- **CSRF 토큰**: 서버가 발급하고 상태 변경 요청에서 검증하는 예측 불가능한 요청 의도 확인값
- **Origin(오리진)**: 요청을 만든 출처의 프로토콜·호스트·포트 정보
- **Referer(리퍼러)**: 현재 요청을 발생시킨 이전 페이지의 주소 정보
- **SameSite(세임사이트)**: 교차 사이트 요청에 쿠키를 전송할 범위를 제한하는 속성
- **안전 메서드**: GET·HEAD처럼 서버 상태를 변경하지 않아야 하는 HTTP 메서드
- **XSS(Cross-Site Scripting, 엑스에스에스)**: 공격 스크립트가 대상 사이트의 브라우저 문맥에서 실행되는 취약점


- **흐름 기호(↓·→·X)**: 아래·다음·차단의 절차 방향과 금지를 표시
## Ⅰ. 개요

- 정의/개념: 자동 인증정보로 상태 변경을 위조함
- 기존 한계: 세션 인증만으로 사용자의 요청 의도 확인 불가
- **배경/필요성**: 상태 변경 요청의 의도와 출처 검증

### 쉽게 이해하기 (학습용)

- CSRF는 로그인 쿠키가 자동 전송되는 점을 악용하므로 서버가 요청 의도까지 검증해야 한다.

## Ⅱ. 특징

- 브라우저의 자동 인증 전송을 악용해 요청을 위조한다.
- 쿠키로 인증하는 모든 상태 변경 경로가 대상이다.
- 안전 메서드에는 서버 상태 변경을 두지 않는다.
- XSS가 있으면 토큰 등 CSRF 방어를 우회할 수 있다.

### 쉽게 이해하기 (학습용)

- 토큰·출처 검사·SameSite 쿠키를 함께 적용하면 위조 요청이 상태 변경까지 도달하기 어렵다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 세션 쿠키 | 자동 첨부된 인증 상태 |
| 상태 변경 경로 | 자금·계정 등 요청 처리 |
| CSRF 토큰 | 요청 의도 검증 값 |
| 출처 정책 | Origin/Referer 검증 |
| 쿠키 정책 | SameSite/안전 메서드 적용 |

```text
[공격 사이트] ─위조 요청─> [사용자 브라우저]
                                │ 세션 쿠키 자동 첨부
                                ↓
                         [상태 변경 서버]
                         토큰·Origin·SameSite 검증
```

### 쉽게 이해하기 (학습용)

- 공격자 페이지가 피해자의 인증 상태를 빌려 요청해도 서버 검증기가 정상 화면에서 발급한 증거가 없으면 거부한다.

## Ⅳ. 원리 및 절차 흐름도

```text
경로식별
   ↓
메서드정리
   ↓
토큰적용
   ↓
출처정책
   ↓
회귀검증
```

| 절차 | 설명 |
|:---|:---|
| 경로식별 | 인증 필요한 상태 변경 경로 식별함 |
| 메서드정리 | 안전 메서드의 상태 변경 제거함 |
| 토큰적용 | 예측 불가능한 토큰 검증함 |
| 출처정책 | SameSite와 출처 정책 적용함 |
| 회귀검증 | 예외 경로 및 보안 정책 검증함 |

> 요약: 상태 변경 경로 식별 후 토큰 및 출처 정책 적용함

### 쉽게 이해하기 (학습용)

- 서버는 상태 변경 요청에서 토큰과 출처를 확인한 뒤에만 업무 처리를 수행한다.

## Ⅴ. 종류 및 비교

| 판단 기준 | CSRF 토큰 | SameSite 쿠키 | 출처 검증 |
|:---|:---|:---|:---|
| 적용 기준 | 의도 직접 검증 | 쿠키 전송 제한 | 출처 판정 시 |
| 핵심 특징 | 비밀 토큰으로 요청 의도 확인 | 교차 사이트 쿠키 전송 제한 | Origin·Referer로 출처 확인 |
| 한계 | 토큰 노출·검증 누락 | 호환성·예외 설정 문제 | 헤더 부재·프록시 처리 오류 |

> 요약: 토큰/SameSite/출처 신호로 위조 의도 판정함

### 쉽게 이해하기 (학습용)

- CSRF과 대안의 선택 기준을 비교함

## Ⅵ. 실무 사례

1. 송금 요청에 **CSRF 토큰 검증**

### 쉽게 이해하기 (학습용)

- 은행 서버는 세션 쿠키만 믿지 않고 송금 폼의 예측 불가능한 CSRF 토큰을 검증해 다른 사이트가 사용자의 권한으로 송금하지 못하게 한다.

## Ⅶ. 결론

- 브라우저의 자동 인증 전송 악용을 막기 위해 상태 변경 여부·토큰 결속·요청 출처·쿠키 정책을 검토하여, 서버가 사용자의 의도를 별도로 검증해야 한다.

### 쉽게 이해하기 (학습용)

- CSRF 방어는 토큰·출처 검사·쿠키 정책과 XSS 제거를 함께 운영해야 한다.
