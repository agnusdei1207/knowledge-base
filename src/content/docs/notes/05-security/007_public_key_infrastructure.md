## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **공개키 기반구조(Public Key Infrastructure, PKI)**: 인증서 발급, 검증, 폐지 수명주기를 통하여 공개키와 소유자 신원을 안전하게 바인딩하는 신뢰 메커니즘.
- **PKI 신뢰 체계(PKI Trust Framework)**: 공인/신뢰 인증기관(CA)의 디지털 서명을 바탕으로 공개키, 신원, 사용 용도를 계층적으로 검증하는 아키텍처.
- **소유자•용도 검증 한계(Limits of Unverified Public Key Usage)**: 검증 체계 없는 단순 공개키 배포 시 위변조 및 임의 소유자 위장 발생하는 한계.

</details>

- 정의/개념: 인증서 수명주기로 공개키와 신원을 묶는 **PKI 신뢰 체계**
- 배경/필요성: 단순 공개키 배포에는 **소유자•용도 검증 한계**가 있다.

#### 한줄 요약

- **CA 서명**으로 공개키•신원을 묶고 **인증서 체인** 제공

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **신뢰 기준점(Trust Anchor)**: 검증자의 신뢰 저장소(Trust Store)에 미리 등록되어 모든 인증서 경로 검증의 최상위 시작점이 되는 루트 인증서.
- **인증기관(Certificate Authority, CA)**: 신원 및 키 통제권을 확인한 후 가입자의 공개키 인증서에 디지털 서명을 수행하는 기관.
- **인증서 체인(Certificate Chain)**: 가입자 인증서에서 시작하여 중간 CA를 거쳐 최상위 루트 CA까지 서명 관계로 상호 연계된 구조.
- **인증서 폐기 목록(Certificate Revocation List, CRL)**: 개인키 유출 등의 사유로 만료 전 효력이 상실된 인증서 일련번호 목록.
- **온라인 인증서 상태 프로토콜(Online Certificate Status Protocol, OCSP)**: 인증서의 실시간 폐기 여부 및 상태를 온라인으로 즉시 조회하는 프로토콜.

</details>

- 계층적 **CA** 구조 기반의 발급 권한 위임 관리
- 최상위 **신뢰 기준점**부터 가입자까지 계층적 **인증서 체인** 검증
- 유효기간과 별개의 **CRL** 및 **OCSP**를 통한 실시간 폐기 상태 대조

#### 한줄 요약

- 최상위 신뢰 기준점(Root CA) 기반 인증서 체인 검증 및 CRL/OCSP를 활용한 실시간 폐기 상태 대조 체계

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트 CA(Root CA)**: 전체 신뢰 체계의 최상위에 위치하며 자체 서명(Self-signed) 인증서를 보유한 핵심 기관.
- **중간 CA(Intermediate CA)**: 루트 CA로부터 서명 권한을 위임받아 특정 영역의 가입자 인증서를 직접 발급 및 관리하는 기관.
- **등록기관(Registration Authority, RA)**: 인증서 발급 신청자의 신원 확인 및 공개키 소지 증명(PoP)을 전담 처리하는 기관.
- **검증자(Relying Party)**: 가입자의 인증서, 서명 및 폐기 목록을 대조하여 서비스 허용 여부를 최종 판정하는 주체.
- **인증서•상태 저장소(Certificate & Status Repository)**: 인증서 체인 정보 및 CRL/OCSP 상태 데이터를 외부에 배포하는 디렉터리 시스템.

</details>

```text
PKI 신뢰 구조
├─ 오프라인 루트 CA
├─ 중간•발급 CA
├─ 등록기관
├─ 인증서•상태 저장소
└─ 가입자•검증자
```

가지의 의미: 신뢰점 관리, 발급, 신원 등록, 상태 배포, 최종 검증 책임을 분리한 구조

| 구성요소 | 책임 |
|:---|:---|
| 오프라인 루트 CA | **최상위 키 격리•권한 위임** |
| 중간•발급 CA | **제한된 정책 범위**의 인증서 서명 |
| 등록기관 | 신청자 **신원•키 통제권** 확인 |
| 인증서•상태 저장소 | **인증서•CRL•OCSP** 상태 배포 |
| 가입자•검증자 | **인증서 체인•신뢰 판정** 수행 |


#### 한줄 요약

- **루트 키 격리•중간 CA 발급•RA 신원 확인**의 책임 분리

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **키 통제권 검증(Proof of Possession, PoP)**: 인증서 신청자가 제출된 공개키에 상응하는 개인키를 실제로 소유하고 있는지 증명함.
- **경로 검증(Certification Path Validation)**: 가입자 인증서로부터 루트 CA까지 서명의 무결성, 제약조건, 유효기간을 체인 검증하는 알고리즘.
- **CA 서명(CA Digital Signature)**: 인증기관이 개인키로 가입자 공개키와 신원 정보 다이제스트에 서명하는 행위.
- **신원•키 통제권 검증(Identity & PoP Validation)**: RA가 신청자의 물리적/논리적 신원과 개인키 소지 여부를 대조하는 단계.
- **검증된 발급 요청(Validated Certificate Request)**: RA의 무결성 검증을 필한 발급 서술자를 CA에 넘기는 단계.
- **인증서 서명(Certificate Signing)**: CA가 가입자의 공개키, 유효기간, 용도 제한 정보를 바인딩하여 서명 발급하는 단계.
- **인증서 경로 검증(Certificate Path Verification)**: 검증자가 저장소의 계층적 인증서 체인을 획득하여 상호 서명을 검증하는 과정.
- **폐기 상태 조회(Revocation Status Lookup)**: CRL 또는 OCSP 응답을 질의하여 현재 인증서 효력 유효성을 확인하는 과정.

</details>

```text
인증서 발급 신청
        │
        ▼
1. 신원•키 통제권 검증
        ├─ 실패: 발급 거부
        └─ 성공
              │
              ▼
     2. 검증된 발급 요청
              │
              ▼
     3. 인증서 서명
              │
              └── 인증서 체인•소유 증명 제시
                          │
                          ▼
                  4. 인증서 경로 검증
                          ├─ 실패: 신뢰 거부
                          └─ 성공
                               │
                               ▼
                       5. 폐기 상태 조회
                               │
                               └── 공개키 신뢰 판정 반환
```

### 동작 원리

1. 신원•키 통제권 검증: RA 기반 신원 대조 및 **키 통제권 검증** 수행
2. 검증된 발급 요청: 신원 검증 완료된 요청을 **검증된 발급 요청**으로 승인
3. 인증서 서명: **CA 서명** 적용을 통한 X.509 **인증서 서명** 발급
4. 인증서 경로 검증: 신뢰 저장소 대조 기반 **인증서 경로 검증** 수행
5. 폐기 상태 조회: CRL 및 OCSP로 현재 인증서 효력 확인


#### 한줄 요약

- **RA 신원•PoP, CA 서명, 체인•폐기 상태** 순차 검증

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **공개 웹 PKI(Public Web PKI)**: 브라우저/OS 신뢰 저장소에 미리 탑재된 글로벌 공인 CA를 사용하는 공개 인터넷 환경의 PKI.
- **사설 조직 PKI(Private Enterprise PKI)**: 특정 기업/기관 내부 단말 및 서버에 사설 루트 CA를 자체 배포하여 운영하는 전용 PKI.

</details>

| PKI 운영 범위 | **공개 웹 PKI** | **사설 조직 PKI** |
|:---|:---|:---|
| 적용 기준 | 불특정 사용자의 공개 서비스 | 관리 가능한 내부 장비•사용자 |
| 핵심 특징 | 공개 신뢰 저장소 CA | 조직 루트 CA•정책 운영 |
| 한계 | 오발급 영향의 공개 확산 | 루트 누락 시 내부 연결 실패 |

> 요약: 서비스 대상 및 검증자 통제 범위에 따른 공개/사설 PKI 아키텍처 선택

#### 한줄 요약

- 불특정 사용자는 **공개 웹 PKI**, 내부 관리 대상은 **사설 PKI** 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **하드웨어 보안 모듈(Hardware Security Module, HSM)**: CA 루트 및 중간 키를 템퍼 리지스턴트(Tamper-resistant) 전용 물리 장비에 내장하여 서명 수행.
- **mTLS(Mutual Transport Layer Security)**: 서버와 클라이언트가 서로의 X.509 인증서를 교환 및 검증하여 양방향 신원을 증명함.
- **RFC 5280(RFC 5280 Standard)**: Internet X.509 PKI 인증서 및 CRL 프로파일과 경로 검증 알고리즘을 규정한 IETF 표준.
- **RFC 6960(RFC 6960 Standard)**: 온라인 인증서 상태 실시간 질의/응답 프로토콜인 OCSP의 메시지 포맷 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인증서 경로 오류 | **RFC 5280** 검증 | 공개키 주체•용도 보장 |
| 실시간 폐지 필요 | **RFC 6960 OCSP** | 유출 인증서 차단 |
| CA 개인키 유출 | **오프라인 루트 CA 및 HSM** | 신뢰점 침해 억제 |
| 내부 상호 인증의 신원 위조 | **사설 PKI 및 mTLS** 적용 | 양방향 신원 검증 |

#### 한줄 요약

- **RFC 5280•6960**, **오프라인 루트•HSM**으로 신뢰 보호

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **검증자 범위(Relying Party Scope)**: 대상 사용자군이 대외 불특정 다수인지, 내부 인프라 구성요소인지에 따른 PKI 배포 정책 수립.

</details>

- 불특정 사용자는 **공개 웹 PKI**, 내부 검증자는 **사설 조직 PKI** 선택

#### 한줄 요약

- **발급•경로 검증•폐기•키 보호**를 통합한 PKI 운영
