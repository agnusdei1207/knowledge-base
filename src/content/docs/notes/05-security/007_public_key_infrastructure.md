## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **공개키 기반구조(Public Key Infrastructure, PKI)**: 인증서의 발급•검증•폐지를 통해 공개키와 소유자의 신원을 연결하는 신뢰 체계이다.
- **PKI 신뢰 체계**: 인증서 수명주기와 인증기관 서명으로 공개키•소유자•용도를 연결하는 체계이다.
- **소유자•용도 검증 한계**: 임의 공개키만으로 실제 소유자와 허용된 사용 목적을 확인하기 어려운 문제이다.

</details>

- 정의/개념: **PKI**는 인증서 수명주기로 공개키와 신원을 연결하는 **PKI 신뢰 체계**이다.
- 배경/필요성: 비대칭키 암호화 시 상대방의 공개키가 위조·변조되지 않았음을 입증할 신뢰 기관 및 발급 체계가 부재하다.

#### 한줄 요약

- 누구나 키 쌍을 생성할 수 있으므로 CA가 공개키 소유자의 신원과 용도를 확인해 서명한 인증서를 발급하고, 검증자는 인증서 체인을 따라 신뢰를 확인한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **신뢰 기준점**: 검증자가 신뢰 저장소에 미리 등록하여 인증서 경로 검증의 출발점으로 삼는 루트 인증서이다.
- **인증기관(Certificate Authority, CA)**: 공개키와 소유자 신원을 확인하여 인증서에 서명하는 기관이다.
- **인증서 체인**: 가입자 인증서부터 중간 CA와 루트 CA까지 서명 관계로 이어진 인증서 목록이다.
- **인증서 폐지 목록(Certificate Revocation List, CRL)**: 폐지된 인증서의 일련번호와 폐지 정보를 배포하는 목록이다.
- **온라인 인증서 상태 프로토콜(Online Certificate Status Protocol, OCSP)**: 특정 인증서의 현재 상태를 온라인으로 조회하는 프로토콜이다.

</details>

- **CA**는 루트와 중간 계층으로 발급 권한을 위임한다.
- **신뢰 기준점**부터 가입자까지 **인증서 체인**을 검증한다.
- 유효기간과 별개로 **CRL**•**OCSP**의 폐지 상태를 확인한다.

#### 한줄 요약

- 인증서가 스스로 믿을 만하다고 주장하는 것은 의미가 없으며, 검증자가 미리 신뢰한 루트 인증서까지 서명이 이어져야 공개키를 믿을 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **루트 CA**: 검증자가 미리 신뢰하는 최상위 인증기관이다.
- **중간 CA**: 루트 CA에서 제한된 인증서 발급 권한을 위임받는 기관이다.
- **등록기관**: 인증서 발급 전에 신청자의 신원과 공개키 통제권을 확인하는 기관이다.
- **검증자**: 인증서의 서명•경로•이름•용도•기간•폐지 상태를 확인하여 공개키 신뢰 여부를 결정하는 주체이다.
- **인증서•상태 저장소**: 인증서 체인과 CRL•OCSP 상태 정보를 배포하는 저장소이다.

</details>

```text
PKI 신뢰 구조
├─ 오프라인 루트 CA
├─ 중간•발급 CA
├─ 등록기관
├─ 인증서•상태 저장소
└─ 가입자•검증자
```

가지의 의미: 신뢰점•발급•등록•상태 배포•검증 책임을 나눈 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 오프라인 루트 CA | **루트 CA**가 최상위 키 격리•권한 위임 |
| 중간•발급 CA | **중간 CA**가 제한된 정책으로 인증서 서명 |
| 등록기관 | **등록기관**이 신청자 신원•키 통제권 확인 |
| 인증서•상태 저장소 | **인증서•상태 저장소**가 인증서 체인•CRL•OCSP 배포 |
| 가입자•검증자 | **검증자**가 인증서 사용과 신뢰 여부 판정 |


#### 한줄 요약

- 루트 CA의 개인키는 오프라인에 보관하고 중간 CA에 제한된 발급 권한만 위임하면, 중간 CA 침해 시에도 루트 인증서 전체를 즉시 교체하지 않아도 된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **키 통제권 검증**: 인증서 신청자가 해당 공개키와 짝을 이루는 개인키를 실제로 보유하는지 확인하는 검증이다.
- **경로 검증**: 가입자 인증서에서 신뢰 기준점까지 서명과 제약 조건이 유효하게 이어지는지 판정하는 검증이다.
- **CA 서명**: 인증기관이 공개키와 주체 정보를 인증서로 연결하는 암호학적 증명이다.
- **신원•키 통제권 검증**: 신청자 신원과 개인키 보유 여부를 등록기관이 확인하는 단계이다.
- **검증된 발급 요청**: 등록기관의 확인 결과를 발급 CA에 제공하는 단계이다.
- **인증서 서명**: CA가 공개키•주체•용도•기간에 서명하는 단계이다.
- **인증서 경로 검증**: 가입자 인증서에서 신뢰 기준점까지 서명과 제약을 확인하는 단계이다.
- **폐지 상태 조회**: CRL•OCSP로 인증서의 현재 효력을 확인하는 단계이다.

</details>

```text
인증서 발급 신청
        │
        ▼
1. 신원•키 통제권 검증
        ├─ 실패: 발급 거부
        └─ 성공
             │
             ▼
     2. 검증된 발급 요청
             │
             ▼
     3. 인증서 서명
             │
             └── 인증서 체인•소유 증명 제시
                         │
                         ▼
                 4. 인증서 경로 검증
                         ├─ 실패: 신뢰 거부
                         └─ 성공
                              │
                              ▼
                      5. 폐지 상태 조회
                              │
                              └── 공개키 신뢰 판정 반환
```

### 동작 원리

1. **신원•키 통제권 검증**: **키 통제권 검증**을 포함한 **신원•키 통제권 검증**을 수행한다.
2. **검증된 발급 요청**: 확인 결과를 **검증된 발급 요청**으로 전달한다.
3. **인증서 서명**: **CA 서명**으로 **인증서 서명**을 수행한다.
4. **인증서 경로 검증**: **경로 검증**으로 **인증서 경로 검증**을 수행한다.
5. **폐지 상태 조회**: CRL•OCSP로 **폐지 상태 조회**를 수행한다.


#### 한줄 요약

- 신분증의 만료일이 남아도 분실 신고가 되면 쓸 수 없듯, 인증서도 기간뿐 아니라 키 유출이나 오발급에 따른 폐지 상태를 확인해야 한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **공개 웹 PKI**: 널리 배포된 공개 신뢰 저장소의 CA를 사용하여 불특정 사용자가 서비스를 검증하는 체계이다.
- **사설 조직 PKI**: 조직이 관리하는 장비와 사용자에게 자체 루트 CA를 배포하여 내부 신뢰를 운영하는 체계이다.

</details>

| PKI 운영 범위 | **공개 웹 PKI** | **사설 조직 PKI** |
|:---|:---|:---|
| 적용 기준 | 불특정 사용자의 공개 서비스 | 관리 가능한 내부 장비•사용자 |
| 핵심 특징 | 공개 신뢰 저장소 CA | 조직 루트 CA•정책 운영 |
| 한계 | 오발급 영향의 공개 확산 | 루트 누락 시 내부 연결 실패 |

> 요약: 검증자 범위로 공개•사설 신뢰를 선택한다.

#### 한줄 요약

- 공개 서비스는 이미 널리 배포된 루트를 사용하고, 사설 조직은 관리하는 장비에 자체 루트를 직접 배포하므로 누가 검증자인지가 선택을 가른다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **하드웨어 보안 모듈(Hardware Security Module, HSM)**: CA 개인키를 외부로 노출하지 않고 내부에서 인증서 서명을 수행하는 장치이다.
- **상호 전송 계층 보안(mutual Transport Layer Security, mTLS)**: 서버와 클라이언트가 인증서를 교환하여 양쪽 신원을 검증하는 방식이다.
- **의견 요청 문서(Request for Comments, RFC) 5280**: 인터넷 X.509 인증서•CRL과 경로 검증 절차를 규정한 표준이다.
- **RFC 6960**: 인증서의 현재 폐지 상태를 온라인으로 질의하고 응답하는 OCSP를 규정한 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인증서 경로 오류 | **RFC 5280** 검증 | 공개키 주체•용도 보장 |
| 실시간 폐지 필요 | **RFC 6960** **OCSP** | 유출 인증서 차단 |
| CA 개인키 유출 | 오프라인 루트•**HSM** | 신뢰점 침해 억제 |
| 내부 상호 인증의 신원 위조 | **사설 조직 PKI**•**mTLS** 적용 | 양방향 신원 검증 |

#### 한줄 요약

- 내부 서비스는 사설 PKI가 서버와 클라이언트에 각각 인증서를 발급하고, mTLS에서 양쪽 체인과 폐지 상태를 검증한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **검증자 범위**: 불특정 외부 사용자를 위한 공개 PKI와 관리 가능한 내부 주체를 위한 사설 PKI의 선택 기준이다.

</details>

- 불특정 검증자는 **공개 웹 PKI**, 관리 단말은 **사설 조직 PKI**를 택하는 **검증자 범위** 판단이 필요하다.

#### 한줄 요약

- 인증서 한 장만 보는 것이 아니라 누가 어떤 절차로 발급했고 검증자가 어느 루트를 믿으며 사고 난 인증서를 어떻게 폐지하는지까지 이어져야 한다.
