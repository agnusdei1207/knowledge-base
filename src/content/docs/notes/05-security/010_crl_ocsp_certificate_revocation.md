## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **인증서 폐지**: 유효기간 전이라도 개인키 유출•오발급•권한 상실이 발생한 인증서를 신뢰 대상에서 제외하는 조치이다.
- **인증기관(Certificate Authority, CA)**: 인증서를 발급하고 폐지 상태에 서명하는 신뢰기관이다.
- **인증서 폐지 목록(Certificate Revocation List, CRL)**: 폐지된 인증서의 일련번호와 사유를 배포하는 목록이다.
- **온라인 인증서 상태 프로토콜(Online Certificate Status Protocol, OCSP)**: 개별 인증서의 현재 상태를 온라인으로 조회하는 프로토콜이다.

</details>

- 정의/개념: 만료 전 **인증서 폐지** 여부를 **CRL**과 **OCSP**로 확인하는 상태 검증이다.
- 배경/필요성: 유효기간 검사만으로는 키가 유출되거나 잘못 발급된 인증서를 차단할 수 없다.

#### 한줄 요약
- 만료일이 남은 신분증도 분실 신고가 되면 사용할 수 없듯, 인증서도 폐지 신고가 검증자에게 전달되면 즉시 거부해야 한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **폐지 정보 전파 지연**: CA가 폐지한 시점과 검증자가 최신 상태를 확인하는 시점 사이의 위험 구간이다.
- **소프트 실패**: 상태 조회가 실패해도 인증서 사용을 허용하는 가용성 우선 정책이다.
- **하드 실패**: 상태 조회가 실패하면 인증서 사용을 거부하는 보안 우선 정책이다.
- **OCSP good**: 폐지 기록이 없다는 뜻이며 인증서의 이름•용도•기간까지 보증하지 않는 상태값이다.

</details>

- **폐지 정보 전파 지연** 동안 인증서 허용 가능성이 핵심이다.
- **OCSP good**은 폐지 기록이 없다는 의미에 한정된다.
- **소프트 실패**는 가용성, **하드 실패**는 보안성 우선이 핵심이다.

#### 한줄 요약

- 폐지 목록에 없다는 것은 분실 신고가 없다는 뜻일 뿐 이름•용도•기간이 맞다는 뜻은 아니므로, 인증서의 다른 조건도 계속 검증해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **CRL 배포점**: CA가 서명한 폐지 인증서 일련번호 목록을 게시하는 저장소이다.
- **OCSP 응답자**: 요청받은 개별 인증서의 상태와 적용 시각을 서명하여 반환하는 서버이다.
- **검증자 캐시**: 서명된 상태 정보를 유효한 기간 동안 재사용하는 저장 영역이다.
- **검증 정책**: 상태 정보의 신선도와 조회 실패 시 허용 여부를 결정하는 기준이다.
- **CA•응답자 검증키**: CRL과 OCSP 응답의 서명을 확인하여 폐지 정보의 출처와 무결성을 보장하는 공개키이다.

</details>

```text
인증서 폐지 검증 구조
├─ CA 폐지 상태 저장소
├─ CRL 배포점
├─ OCSP 응답자
├─ 검증자 캐시•정책
└─ CA•응답자 검증키
```

가지의 의미: 상태 보관•배포•응답•판정•서명 검증 책임을 나눈 구조다.

| 구성요소 | 책임 |
|:---|:---|
| CA 폐지 상태 저장소 | 폐지 일련번호•사유•시각 보관 |
| CRL 배포점 | **CRL 배포점**에 서명된 폐지 목록 게시 |
| OCSP 응답자 | **OCSP 응답자**가 인증서별 상태•적용 시각 서명 |
| 검증자 캐시•정책 | **검증자 캐시**와 **검증 정책**으로 신선도•조회 실패 처리 결정 |
| CA•응답자 검증키 | **CA•응답자 검증키**로 CRL•OCSP 응답 출처 검증 |


#### 한줄 요약

- 폐지 정보도 공격자가 바꾸거나 오래된 정상 응답을 다시 보낼 수 있으므로, 검증자는 서명과 갱신 시각을 함께 확인한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **thisUpdate**: 상태 정보가 생성된 기준 시각이다.
- **nextUpdate**: 다음 상태 정보가 제공되어야 하는 한계 시각이다.
- **서명 검증**: 폐지 정보의 출처가 CA 또는 위임 응답자인지 확인하는 절차이다.
- **신선도 검증**: 상태 응답이 현재 시점에도 유효한지 확인하는 절차이다.
- **실패 정책**: 상태 조회가 불가능할 때 서비스 위험에 따라 인증서를 허용하거나 거부하는 기준이다.
- **서명 CRL 게시**: 폐지 일련번호와 적용 시각을 담은 CRL에 CA가 서명하여 배포하는 단계이다.
- **인증서 상태 동기화**: CA의 최신 폐지 상태를 OCSP 응답자에 반영하는 단계이다.
- **서명•신선도 검증**: 상태 정보의 출처 서명과 현재 시점의 유효성을 함께 확인하는 단계이다.
- **실패 정책 적용**: 상태 조회 실패 또는 오래된 응답을 서비스 위험 기준에 따라 허용하거나 거부하는 단계이다.

</details>

```text
CA 폐지 상태 갱신
        ├─ 1. 서명 CRL 게시
        └─ 2. 인증서 상태 동기화
                    │
                    └── CRL•OCSP 상태 조회
                              │
                              ▼
                      3. 서명•신선도 검증
                              ├─ 폐지: 인증서 거부
                              ├─ 정상: 다른 인증서 조건 검증
                              └─ 조회 실패•오래된 상태
                                         │
                                         ▼
                                 4. 실패 정책 적용
                                         ├─ 소프트 실패: 위험 수용
                                         └─ 하드 실패: 인증서 거부
```

### 동작 원리

1. **서명 CRL 게시**: 폐지 일련번호•시각을 배포한다.
2. **인증서 상태 동기화**: 응답자에 최신 폐지 상태를 반영한다.
3. **서명•신선도 검증**: **서명 검증**으로 출처를 확인하고 **신선도 검증**으로 **thisUpdate**•**nextUpdate**을 확인한다.
4. **실패 정책 적용**: 위험에 따라 소프트•하드 실패를 선택한다.


#### 한줄 요약

- 상태 서버가 안 보일 때 무조건 허용하면 공격자가 조회를 방해해 폐지 인증서를 계속 쓸 수 있고, 무조건 거부하면 상태 장애가 서비스 중단으로 이어진다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 구간 보호를 제공하는 프로토콜이다.
- **OCSP 스테이플링**: 서버가 미리 받은 서명 OCSP 응답을 TLS 연결에 첨부하여 검증자에게 전달하는 방식이다.

</details>

| 인증서 폐지 확인 | CRL | OCSP | OCSP 스테이플링 |
|:---|:---|:---|:---|
| 적용 기준 | 대량 검증•폐쇄망 | 최신 개별 상태가 필요한 검증 | **TLS**의 조회 지연•노출 완화 |
| 핵심 특징 | **CRL**로 폐지 목록 일괄 검사 | **OCSP**로 인증서별 온라인 질의 | **OCSP 스테이플링**으로 서명 응답 첨부 |
| 한계 | 목록 증가•배포 지연 | 응답 장애•조회 정보 노출 | 서버의 응답 갱신 누락 |

> 요약: 목록 규모•신선도•조회 경로로 선택한다.

#### 한줄 요약

- CRL은 전체 분실자 명단을 받아 두고 찾으며, OCSP는 신분증 하나씩 물어보고, 스테이플링은 서버가 미리 받은 공식 답변을 함께 내민다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **의견 요청 문서(Request for Comments, RFC) 5280**: 인터넷 X.509 인증서와 CRL 프로파일 및 검증 절차를 규정한 국제 표준 문서이다.
- **RFC 6960**: 인증서별 현재 상태를 질의하고 응답하는 OCSP를 규정한 국제 표준 문서이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| CRL 형식•검증 오류 | **RFC 5280** 적용 | 목록 상호운용성 확보 |
| OCSP 상태•신선도 오류 | **RFC 6960** 검증 | 재전송•오판정 억제 |
| 상태 서비스 장애 | 위험별 **실패 정책**•**검증자 캐시** 적용 | 보안•가용성 균형 |

#### 한줄 요약

- 공개 TLS 서버가 최신 OCSP 응답을 연결에 첨부하면 클라이언트가 인증기관에 직접 질의하지 않고도 폐지 상태를 확인할 수 있다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **폐지 확인 방식 선택**: 목록 규모•필요한 신선도•조회 경로의 가용성과 장애 시 위험을 함께 고려하는 결정 기준이다.

</details>

- **폐지 확인 방식 선택**에 따라 대량•폐쇄망은 **CRL**, 공개 TLS의 저지연 검증은 **OCSP 스테이플링**을 선택한다.

#### 한줄 요약

- 새 폐지 정보의 도착 시점과 조회 실패 때 연결 허용 여부를 서비스 위험에 맞춰 정한다.
