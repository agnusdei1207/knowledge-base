## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **소프트웨어 공급망(Software Supply Chain)**: 소스•의존성•빌드•저장소•배포를 거쳐 소프트웨어가 만들어지는 전체 연결 구조를 의미함.
- **전이 의존성(Transitive Dependency)**: 개발자가 직접 선택한 구성요소가 하위로 포함하는 간접 의존성 지칭.

</details>

- 정의/개념: 소스부터 배포까지 구성요소의 출처와 무결성을 검증하는 보안 체계
- 배경/필요성: 전이 의존성에 포함된 취약 및 오염 구성요소의 영향 범위 은폐 위험 차단 필요

#### 한줄 요약

- 완성 프로그램만 검사하지 않고 구성요소의 출처와 빌드 파이프라인 및 취약점의 실제 영향을 함께 확인한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **소프트웨어 자재명세서(Software Bill of Materials, SBOM)**: 제품의 구성 부품•버전•관계를 기록한 표준 명세서.
- **취약점 악용 가능성 교환(Vulnerability Exploitability eXchange, VEX)**: 제품별 취약점 영향 상태와 판단 근거를 전달하는 양식.
- **출처 증명(Provenance)**: 산출물을 누가 어떤 소스•도구•과정으로 만들었는지 나타내는 검증 정보 기술.

</details>

- **SBOM**과 **VEX** 기반 구성 요소 및 제품별 영향 판별
- 격리 빌드 및 전자서명을 통한 산출물 변조 차단
- **출처 증명**과 승격 정책 기반 배포 신뢰성 검증

#### 한줄 요약

- SBOM에 취약 부품이 있어도 모두 위험한 것은 아니므로 VEX의 영향 근거와 문서 발행자•최신성을 함께 확인한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **격리 빌드(Isolated Build)**: 작업별 권한•파일•네트워크를 분리한 환경에서 산출물을 생성하는 방식.
- **단명 자격(Ephemeral Credentials)**: 하나의 빌드 작업과 짧은 시간에만 유효한 인증 정보에 해당함.
- **불변 저장소(Immutable Repository)**: 같은 식별자의 산출물을 덮어쓰지 못하게 보관하는 저장소.
- **배포 게이트(Deployment Gate)**: 서명•증적 정책을 통과한 산출물만 운영으로 승격하는 통제 메커니즘.

</details>

```text
[소스•의존성 제어] ----- [격리 빌드] ----- [산출물•서명]
                                                |
                                    [SBOM•VEX•출처]
                                                |
                                    [검증•배포 게이트]
```

선 의미: 승인된 소스•의존성, 격리 빌드 환경, 서명 산출물 및 결속 증적 기반 정적 공급망 신뢰 경계 표현

| 구성요소 | 책임 |
|:---|:---|
| 소스•의존성 제어 | 승인 출처•고정 버전 관리 |
| 격리 빌드 | **단명 자격**과 **격리 빌드**로 산출물 생성 |
| 산출물•서명 | 해시•서명과 **불변 저장소**로 변조 차단 |
| SBOM•VEX•출처 | 구성•영향 정보와 생산 이력 제공 |
| 검증•배포 게이트 | **배포 게이트**가 증적•승격 정책 집행 |

#### 한줄 요약

- 승인한 의존성을 격리 환경에서 빌드하고 산출물과 빌드 이력을 서명한 뒤 검증을 통과한 결과만 배포한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **서명 산출물(Signed Artifact)**: 무결성과 발행 주체를 확인할 수 있도록 전자서명을 결합한 빌드 결과물.
- **증적(Attestation)**: SBOM•VEX•출처 정보를 산출물과 결속해 보존한 검증 자료를 일컫음.
- **운영 영향 추적(Operational Impact Tracking)**: 새 취약점 발견 시 영향 제품•실행 가능성•수정 상태를 배포 산출물까지 연결하는 과정.
- **출처•버전•해시 검증(Provenance, Version, Hash Verification)**: 소스와 의존성이 승인된 위치•고정 버전•예상 해시와 일치하는지 확인하는 단계.
- **격리 빌드•산출물 서명(Isolated Build & Artifact Signing)**: 단명 자격을 사용한 분리 환경에서 결과를 만들고 서명하는 단계.
- **불변 저장•증적 결속(Immutable Storage & Attestation Binding)**: 산출물을 덮어쓸 수 없게 보관하고 SBOM•VEX•출처 정보를 결합하는 단계.
- **서명•영향•승격 정책 검증(Signature, Impact & Promotion Policy Verification)**: 전자서명과 취약점 영향이 운영 배포 기준을 충족하는지 판정하는 단계.
- **배포•운영 구성 연계(Deployment & Runtime Configuration Linking)**: 운영 환경의 산출물과 구성 증적을 연결해 신규 취약점 영향을 추적하는 단계.

</details>

```text
[승인 소스•의존성]
          |
          v
1. 출처•버전•해시 검증
          |
          v
2. 격리 빌드•산출물 서명
          |
          `-- 서명 산출물•증적
                      |
                      v
[산출물 저장소]
          |
          v
3. 불변 저장•증적 결속
          |
          v
[배포 게이트]
          |
          v
4. 서명•영향•승격 정책 검증
          |
          v
[운영 환경]
          |
          v
5. 배포•운영 구성 연계
          |
          v
+----------------------------------+
| 운영 중 신규 취약점 발견         |
|                                  |
|  신규 취약점•배포 구성           |
|             |                    |
|             v                    |
|  영향 제품•조치 우선순위 환류    |
+----------------------------------+
```

### 동작 원리

1. **출처•버전•해시 검증**: 승인 소스와 고정 의존성의 출처•버전•해시 검증 수행
2. **격리 빌드•산출물 서명**: 단명 자격 기반 격리 빌드 및 산출물 서명 집행
3. **불변 저장•증적 결속**: 산출물 불변 저장 및 **증적** 결속 처리
4. **서명•영향•승격 정책 검증**: **서명 산출물**의 서명•영향•승격 정책 검증
5. **배포•운영 구성 연계**: 신규 취약점의 **운영 영향 추적**을 위한 배포•운영 구성 연계

#### 한줄 요약

- 배포 게이트는 산출물과 SBOM•VEX•출처 증명을 검증하고 운영 중 새 취약점의 영향과 조치 상태를 다시 연결한다.

## Ⅴ. 종류 및 비교

| 공급망 증적 | 담당 역할 | 결합 효과 |
|:---|:---|:---|
| **SBOM** | 부품•버전•관계 기록 | 영향받는 구성요소 식별 |
| **VEX** | 제품별 취약점 영향 상태 기록 | 조치 우선순위와 예외 근거 제공 |
| **출처 증명** | 생산 주체•빌드 과정 기록 | 산출물 출처•무결성 검증 |

#### 한줄 요약

- SBOM은 구성요소 목록, VEX는 취약점 영향 판정서, 출처 증명은 빌드 이력이며 세 증적을 배포 관문에 연결해야 한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-218 SSDF 1.1(NIST Secure Software Development Framework 1.1, SSDF)**: 안전한 개발 관행을 SDLC에 통합하는 미국 국립표준기술연구소 지침.
- **SLSA 1.2(Supply-chain Levels for Software Artifacts 1.2, SLSA)**: 소스•빌드 출처와 무결성 보증 수준을 제시하는 프레임워크.
- **소프트웨어 개발 생명주기(Software Development Life Cycle, SDLC)**: 요구•설계•개발•시험•배포•운영의 전체 개발 과정 지칭.
- **CISA VEX 최소 요구사항(CISA VEX Minimum Requirements)**: 취약점 영향 상태와 판단 근거의 필수 필드를 정의한 요구사항.
- **재현 빌드(Reproducible Build)**: 같은 소스와 조건에서 동일한 산출물을 다시 생성해 변조를 대조하는 방식.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 개발 관행 불일치로 통제 공백 발생 | **NIST SP 800-218 SSDF 1.1** 적용 | **SDLC** 공급망 위험 축소 |
| VEX 필드 불일치로 자동 연계 실패 | **CISA VEX 최소 요구사항** 적용 | 상태•근거 상호운용성 확보 |
| 출처 증명 위조 시 오염 판별 실패 | **SLSA 1.2**•서명•최신성 검증 | 오염 산출물 승격 차단 |
| 빌드 재현 불가 시 변조 원인 추적 곤란 | **재현 빌드**로 결과 대조 | 빌드 변조 탐지력 향상 |

#### 한줄 요약

- Log4j 사고에서는 SBOM으로 포함 제품을 찾고 VEX로 실제 실행 영향을 판단하며 서명과 최신성이 검증된 결과만 조치 우선순위에 쓴다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **산출물 승격 조건(Artifact Promotion Criteria)**: 서명과 출처가 유효하고 구성•취약점 영향이 정책상 허용될 때만 운영 환경으로 배포하는 평가 기준.

</details>

- **산출물 승격 조건**에 따라 서명•출처 유효성 및 VEX 영향 허용 시에만 운영 배포 수행

#### 한줄 요약

- 공급망 보안의 성패는 문서 보유량이 아니라 신뢰할 수 있는 소스와 빌드에서 나온 산출물만 배포하고 새 취약점 영향을 즉시 찾는 데 달려 있다.
