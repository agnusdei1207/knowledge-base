## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **프롬프트 인젝션 (Prompt Injection)**: 시스템 지침(System Prompt)과 사용자 입력(User Input)이 자연어로 동일한 채널에 주입되는 취약점을 악용하여, LLM의 원래 행동 규칙을 하이재킹(Hijacking)하는 치명적 공격 기법이다.
- **지침·데이터 혼동 (Instruction-Data Confusion)**: 과거 폰 노이만 아키텍처의 코드/데이터 혼동처럼, 자연어 프롬프트 텍스트에서 '제어 지침(Instruction)'과 비신뢰 '참조 데이터(Data)'를 명확히 분리 구분하지 못하는 LLM의 구조적 한계이다.

</details>

- 정의: 사용자의 악의적인 비신뢰 입력을 통해 LLM에 사전 부여된 시스템 지침을 무효화시키고 공격자가 원하는 비인가 조작을 유도하는 AI 해킹 기법이다.
- 배경: LLM은 자연어로 된 지침과 데이터를 동일한 텍스트 스트림으로 처리하기 때문에, 교묘하게 작성된 공격 구문이 최우선 제어 지시로 오인되는 지침·데이터 혼동이 발생하기 때문이다.

#### 한줄 요약

- 지침·데이터 혼동 취약점을 악용하여 악의적 입력으로 시스템 지침을 무력화하고 모델을 조종하는 공격 기법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **직접 인젝션 (Direct Prompt Injection)**: 공격자가 프롬프트 입력창을 통해 "이전 모든 지침을 무시하라"는 등 시스템 프롬프트를 무력화하는 명령을 직접 주입하는 공격 경로이다.
- **간접 인젝션 (Indirect Prompt Injection)**: 웹페이지, 이메일, RAG 탐색 문서 내에 은밀히 삽입된 악성 프롬프트 텍스트를 LLM이 수용하면서 의도치 않게 악성 동작을 수행하는 공격 경로이다.
- **RAG (검색 증강 생성 / Retrieval-Augmented Generation)**: 외부 벡터 DB에서 조회된 텍스트 문맥을 LLM 프롬프트에 동적으로 조합하여 응답을 생성하는 아키텍처 패턴이다.
- **피해 범위 제한 (Blast Radius Reduction)**: 인젝션 공격이 성공하더라도 에이전트의 권한 및 샌드박스를 통제하여 인프라 손상 및 데이터 유출 피해를 국소화하는 보안 원칙이다.

</details>

- **공격 경로 다변화**: 대화창을 통한 **직접 인젝션** 및 RAG 외부 문서를 거쳐 들어오는 **간접 인젝션** 기반 침투 경로가 다변화된다.
- **구조적 방어 한계**: 프롬프트 문자열 이스케이프(Escape) 방식이나 단순 필터링만으로는 자연어 특성상 100% 방어가 불가능한 한계를 지닌다.
- **피해 범위 국소화**: 공격 자체의 완전 차단이 어렵기 때문에, **피해 범위 제한** 원칙에 따라 런타임 가드레일(Guardrails), 최소 권한 IAM, 독립 정책 집행점(PEP) 조치를 융합 적용한다.

#### 한줄 요약

- 직접 및 간접 인젝션 경로로 침투하며, 자연어 통제의 한계를 극복하기 위해 런타임 가드레일 및 샌드박스로 피해 범위를 제한한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **시스템 프롬프트 (System Prompt)**: 시스템 설계자가 LLM에 페르소나, 역할, 안전 거부 규칙, 응답 제약사항을 고정적으로 지정한 고권한 지침 텍스트이다.
- **사용자 프롬프트 (User Prompt)**: 최종 사용자가 대화창이나 API 요청을 통해 LLM에 전달하는 비신뢰 입력 텍스트이다.
- **정책 집행점 (Policy Enforcement Point, PEP)**: LLM이 생성한 Tool Call이나 응답 텍스트를 런타임에 중간 인터셉트하여 최종 인가 여부를 판단하는 통제 게이트웨이이다.

</details>

```text
[프롬프트 인젝션 철저한 방어 체계]
                  |
                  +-- [1. 시스템 지침 및 사용자 입력 완전 격리]
                  +-- [2. RAG 외부 콘텐츠 출처 검증]
                  +-- [3. 모델 추론 시 지침 우선순위 강제]
                  +-- [4. 응답 및 API 도구 호출 데이터화]
                  `-- [5. 독립 정책 집행점(PEP) 최종 권한 검증]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **지침 / 입력 경계** | **시스템 프롬프트** 및 **사용자 프롬프트** 활용 XML/JSON 태그로 물리적·논리적 완전 격리 | Boundary |
| **외부 콘텐츠 처리** | **RAG** 파이프라인에서 추출된 외부 문서의 출처 및 인젝션 악성 구문 사전 검사 | Sanitization |
| **모델 / 문맥 제어** | LLM 추론 시 시스템 지침의 우선순위를 강화하고 비신뢰 데이터의 가중치를 통제 | Model Weight |
| **응답 / 도구 제안** | LLM이 외부 API 호출(Tool Call)을 요청할 때 인자값의 이스케이프 및 안전한 구조화 | Output Format |
| **정책 및 권한 검증** | **정책 집행점(PEP)** 이 LLM 요청 액션을 최종 사용자의 IAM 최소 권한 범위와 2차 대조 | Authorization |

#### 한줄 요약

- 시스템 및 사용자 프롬프트를 명확히 태깅하여 격리하고, LLM의 출력 및 Tool Call을 독립 PEP에서 철저히 검증 집행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **사용자 재승인 (Human-in-the-Loop)**: AI 에이전트가 데이터 삭제, 이체 등 고위험 액션을 수행하려 할 때 최종 인간의 명시적 승인을 강제하는 절차이다.
- **거래 결속 (Transaction Binding)**: 사용자가 최초 동의한 거래 파라미터(수신자, 금액 등)를 세션에 암호학적으로 고정하여 인젝션 변조를 막는 기술이다.
- **샌드박스 (Sandbox)**: LLM이 제안한 파이썬 코드나 OS 명령어를 실제 시스템 자원과 완전히 격리된 환경 내에서만 실행하는 통제 영역이다.

</details>

```text
[공격자의 상위 지침 무시 악성 입력]
                  |
                  v
1. 시스템 지침 및 사용자 비신뢰 문맥 결합
                  |
                  v
2. LLM 내부 지침·비신뢰 데이터 혼동 발생
                  |
                  v
3. 공격자의 악성 지시를 최우선 지침으로 해석
                  |
                  `-- 조작된 응답 및 과권한 도구 호출 제안
                              |
                              v
[보안 정책 집행점(PEP) 부재 시]
                              |
                              v
4. 독립 권한 대조 및 내용 검증 절차 누락
                              |
                              `-- 과도한 권한의 API 도구 호출
                                          |
                                          v
                              5. 비승인 정보 무단 접근 및 상태 변경
                                          |
                                          v
                              [조작된 응답 반환 및 침해 결과 발생]
```

### 동작 원리

1. 문맥 결합: 시스템 지침과 악의적 외부 입력이 단일 문맥으로 결합된다.
2. 지침 오인 혼동: LLM이 악성 입력 구문을 상위 제어 지침으로 착각한다.
3. 공격 지시 채택: 기존 지침을 무시하고 비인가 조회나 호출 액션을 생성한다.
4. 검증 절차 누락: PEP 등의 안전 방어망 없이 과권한 도구 호출을 수용한다.
5. 시스템 침해: 데이터 유출 및 시스템 상태의 비인가 변조가 발생한다.

#### 한줄 요약

- 악성 입력 주입, 지침/데이터 혼동, 공격 지시 채택, PEP 검증 누락 및 비승인 시스템 조작 결과 발생으로 이어진다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **탈옥 (Jailbreak Attack)**: 롤플레이(DAN 등), 가상 시나리오, 2중 암호화 기법을 이용해 LLM의 윤리적/안전성 거부 필터를 무력화하는 직접 인젝션의 변종 공격이다.

</details>

| 프롬프트 공격 유형 | **직접 프롬프트 인젝션 (Direct)** | **간접 프롬프트 인젝션 (Indirect)** | **탈옥 공격 (Jailbreak)** |
|:---|:---|:---|:---|
| 공격 진입 경로 | 사용자의 직접적인 대화창 (User Prompt) 입력 | RAG 검색 문서, 이메일, 웹사이트 등 매복 매체 | 교묘하게 설계된 사용자의 페르소나 설정 및 우회 텍스트 |
| 공격 주 목적 | 시스템 프롬프트 유출 및 보안 지침 무력화 | 비인가 데이터 유출, 악성 도구 실행 및 C2 서버 통신 | 금지된 해킹/범죄 정보 및 윤리 위반 응답 무단 도출 |
| 핵심 방어 기술 | XML 태깅 분리 및 LLM Input Guardrails | **RAG** 데이터 출처 검증 및 **PEP** 독립 2차 철저한 검증 | RLHF/DPO 안전성 정렬 강화 및 출력 샌드박싱 |

#### 한줄 요약

- 직접 인젝션은 대화창 지침 무효화, 간접 인젝션은 RAG 문서 기반 침투, 탈옥은 안전 정렬 필터 우회에 집중한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OWASP LLM01:2025 (OWASP Top 10 for LLM Applications)**: 글로벌 표준 기구 OWASP가 최우선 LLM 애플리케이션 보안 위험 1위로 지정한 프롬프트 인젝션 위협 규격이다.
- **MITRE ATLAS AML.T0051**: MITRE ATLAS에 등록된 LLM 프롬프트 인젝션 공격 기술 식별 코드이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| **최우선 LLM 위협 방어 기준 가이드 미비** | 체계적 인젝션 방어 프레임워크 부재 | **OWASP LLM01:2025** 통제 기준 전면 준용 | 직접/간접 프롬프트 인젝션에 대한 일관성 있는 방어 수립 |
| **신종 AI 공격 기법 탐지 시그니처 부재** | 전통 웹 방화벽(WAF)의 자연어 우회 탐지 한계 | **MITRE ATLAS AML.T0051** 매핑 및 LLM WAF 룰 반영 | TTPs 기반 AI 위협 탐지 시그니처 최신화 및 사전 차단 |
| **간접 인젝션으로 인한 비인가 도구 무단 실행** | LLM 제안 도구를 맹목적으로 신뢰하여 즉시 자동 실행 | **PEP** 기반 2차 검증, **단명 자격** 부여 및 **사용자 재승인** | LLM이 속더라도 런타임 샌드박스 통제로 실질적 비인가 액션 무력화 |

#### 한줄 요약

- OWASP LLM01:2025 및 MITRE ATLAS AML.T0051 지침을 적용하고, 런타임 PEP 및 Human-in-the-loop 조치를 수립한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **실패 격리 (Failure Containment)**: LLM이 프롬프트 인젝션 공격에 넘어가 악성 명령을 생성하더라도, 런타임 샌드박스 및 PEP에 의해 실제 시스템 손상이 발생하지 않도록 차단하는 안전 아키텍처이다.

</details>

- 프롬프트 텍스트 차단의 본질적 한계를 극복하고 중심 방어를 구현하기 위해, XML 태그 기반 입력 격리, 런타임 **PEP** 가드레일, 그리고 완벽한 **실패 격리(Failure Containment)** 중심 방어 체계 확립 필수이다.

#### 한줄 요약

- 인젝션 예방 필터와 독립 PEP 가드레일 기반 실패 격리 아키텍처 적용
