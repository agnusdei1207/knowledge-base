## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **프롬프트 인젝션(Prompt Injection)**: 비신뢰 입력이 모델의 지침 해석을 교란하여 원래 규칙과 다른 출력이나 행동을 유도하는 공격 기법.
- **인공지능(Artificial Intelligence, AI)**: 학습된 모델로 인식•추론•생성 작업을 수행하는 기술 지칭.
- **대규모 언어 모델(Large Language Model, LLM)**: 대규모 언어 데이터로 학습해 자연어를 이해•생성하는 인공지능 모델.
- **지침•데이터 혼동(Instruction-Data Confusion)**: 자연어로 함께 전달된 상위 지시와 비신뢰 자료를 모델이 구분하지 못하는 구조적 한계.

</details>

- 정의/개념: AI 시스템의 LLM이 비신뢰 입력을 상위 지침으로 오인하도록 유도하는 프롬프트 인젝션 공격
- 배경/필요성: 자연어 처리 환경에서 지침과 비신뢰 데이터의 완전 분리 한계 극복 필요

#### 한줄 요약

- 모델이 읽은 비신뢰 문장을 데이터가 아니라 새 명령으로 받아들여 원래 규칙과 다른 답이나 행동을 만드는 문제이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **직접 인젝션(Direct Prompt Injection)**: 공격 지시가 사용자의 대화 입력에 직접 포함되는 공격 경로.
- **간접 인젝션(Indirect Prompt Injection)**: 공격 지시가 검색•웹•메일 같은 외부 자료를 통해 유입되는 경로 지칭.
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: 외부 자료를 검색해 모델의 생성 문맥에 결합하는 검색 생성 방식.
- **피해 범위 제한(Blast Radius Reduction)**: 독립 정책•최소 권한으로 모델 실패가 실제 실행으로 이어지는 범위를 줄이는 통제 원칙.

</details>

- **직접 인젝션**은 사용자 입력, **간접 인젝션**은 **RAG** 자료 기반 비신뢰 지시 유입
- 프롬프트 은닉만으로 완전 차단 불가능한 구조적 한계 존재
- **피해 범위 제한**을 위한 독립 정책 및 최소 권한 기반 실행 통제

#### 한줄 요약

- 공격 문장을 모두 찾아내기 어려우므로 모델이 속아도 민감정보를 읽거나 중요한 도구를 바로 실행하지 못하게 해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **시스템 프롬프트(System Prompt)**: 서비스가 모델에 제공하는 상위 지침과 행동 규칙.
- **사용자 프롬프트(User Prompt)**: 사용자가 모델에 전달하는 요청과 대화 입력.
- **출처(Provenance)**: 외부 자료가 생성•수집된 위치와 신뢰 수준을 나타내는 정보.
- **정책 집행점(Policy Enforcement Point, PEP)**: 모델 제안을 별도 규칙과 사용자 권한으로 검증•집행하는 경계 지칭.

</details>

```text
[프롬프트 인젝션 통제]
          |
          +-- [지침•입력 경계]
          +-- [외부 콘텐츠 처리]
          +-- [모델•문맥]
          +-- [응답•도구 제안]
          `-- [정책•권한 검증]
```

선 의미: 입력 신뢰, 모델 문맥, 출력 제안, 권한 집행 절차의 정적 신뢰 경계 표현

| 구성요소 | 책임 |
|:---|:---|
| 지침•입력 경계 | **시스템 프롬프트**•**사용자 프롬프트**와 외부 자료 분리 |
| 외부 콘텐츠 처리 | **RAG**와 **출처** 정보를 통한 신뢰 수준 표시 |
| 모델•문맥 | 응답 및 도구 호출 제안 생성 |
| 응답•도구 제안 | 구조화된 출력 및 대상 자원 정보 제공 |
| 정책•권한 검증 | **정책 집행점(PEP)**에서 실행 조건 재검증 |

#### 한줄 요약

- 모델은 답과 행동을 제안할 뿐이며 별도 정책 경계가 실제 사용자 권한과 대상 자원을 확인한 뒤 실행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **사용자 재승인(User Re-approval)**: 고위험 행동의 대상•내용•영향을 보여 주고 실행 전에 다시 동의를 받는 사람 개입 통제.
- **거래 결속(Transaction Binding)**: 사용자가 승인한 매개변수를 실제 실행 요청과 변경 불가능하게 묶는 통제 메커니즘.
- **샌드박스(Sandbox)**: 도구의 파일•네트워크•실행 권한을 격리한 제한 환경.
- **단명 자격(Ephemeral Credentials)**: 하나의 작업과 짧은 시간에만 유효한 최소 권한 인증 정보 지칭.
- **시스템•사용자 문맥 결합(System & User Context Assembly)**: 신뢰 수준이 다른 시스템 지침과 사용자 입력을 하나의 문맥으로 구성하는 단계.
- **지침•비신뢰 데이터 혼동(Instruction & Untrusted Data Confusion)**: 모델이 사용자 입력이나 외부 자료를 실행 지침으로 오인하는 단계.
- **공격 지시 우선 해석(Attack Instruction Precedence)**: 모델이 원래 정책보다 주입된 지시를 우선해 출력•행동 후보를 만드는 단계.
- **독립 권한•내용 검증 누락(Independent Permission & Content Verification Omission)**: 모델의 행동 제안을 별도 실행 정책으로 재검증하지 않는 단계.
- **비승인 정보 접근•상태 변경(Unauthorized Information Access & State Modification)**: 과도한 도구 권한으로 허가되지 않은 조회나 변경이 발생하는 단계.

</details>

```text
[상위 지침 무시•도구 실행 입력]
          |
          v
1. 시스템•사용자 문맥 결합
          |
          v
2. 지침•비신뢰 데이터 혼동
          |
          v
3. 공격 지시 우선 해석
          |
          `-- 응답•도구 제안
                    |
                    v
[정책 집행점(PEP)]
          |
          v
4. 독립 권한•내용 검증 누락
          |
          `-- 과도한 권한 도구 호출
                    |
                    v
5. 비승인 정보 접근•상태 변경
          |
          v
[조작된 응답•행동 결과]
```

### 동작 원리

1. **시스템•사용자 문맥 결합**: 신뢰 수준이 다른 자연어 지침과 입력의 병합 구성
2. **지침•비신뢰 데이터 혼동**: 사용자 문장에 포함된 비신뢰 데이터를 실행 지침으로 오인
3. **공격 지시 우선 해석**: 원래 정책과 다른 무단 출력 및 행동 후보 산출
4. **독립 권한•내용 검증 누락**: 모델의 행동 제안을 별도 정책 검증 없이 수용
5. **비승인 정보 접근•상태 변경**: 과도한 도구 권한으로 인한 정보 유출 및 상태 변조 발생

#### 한줄 요약

- 모델이 악성 지시를 따르더라도 샌드박스와 단명 자격으로 실행 범위를 줄이고 거래 결속과 사용자 재승인으로 허용된 행동만 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **탈옥(Jailbreak Attack)**: 모델의 안전 거부 정책을 우회해 금지된 응답을 얻으려는 공격 기법 지칭.

</details>

| 프롬프트 공격 유형 | 직접 인젝션 | 간접 인젝션 | 탈옥 |
|:---|:---|:---|:---|
| 적용 기준 | **직접 인젝션** | **간접 인젝션** | **탈옥** |
| 핵심 특징 | 사용자 지시 유입 | 외부 자료 지시 유입 | 안전 거부 정책 우회 |
| 한계 | 입력 필터를 피하는 변형 공격 반복 | 출처 확장•지연 발동 위험 | 정책 일관성 저하 가능 |

#### 한줄 요약

- 직접형은 사용자가 공격하고 간접형은 모델이 읽는 자료가 공격하며 탈옥은 주로 금지 응답의 거부 규칙을 우회한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **OWASP(Open Worldwide Application Security Project)**: 애플리케이션 보안 지침을 공개하는 비영리 프로젝트.
- **OWASP LLM01:2025(OWASP Top 10 for LLM Applications 2025 - LLM01 Prompt Injection, LLM01:2025)**: 직접•간접 프롬프트 인젝션을 LLM 응용의 최우선 위험으로 분류한 항목.
- **MITRE ATLAS(Adversarial Threat Landscape for AI Systems, ATLAS)**: AI 시스템 공격 전술•기법을 분류하는 MITRE 지식베이스.
- **MITRE ATLAS AML.T0051(ATLAS LLM Prompt Injection, AML.T0051)**: LLM 프롬프트 인젝션과 하위 기법을 식별하는 ATLAS 항목 지칭.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위협 유형 누락으로 시험 범위 축소 | **OWASP** **LLM01:2025** 적용 | 직접•간접 공격 시나리오 확보 |
| 공격 기법 추적 단절로 대응 공유 곤란 | **ATLAS** **AML.T0051** 매핑 | 직접•간접 하위 기법 추적 |
| 모델 권한 오판 시 유출•변경 확산 | **PEP**와 **단명 자격** 적용 | 유출•변경 피해 범위 제한 |
| 고위험 외부 행동을 자동 승인할 위험 | **거래 결속**과 **사용자 재승인** 적용 | 승인 대상 불일치•무단 실행 방지 |

#### 한줄 요약

- 고객 챗봇이 이전 지시를 무시하라는 요청을 받아도 정책 집행점은 비밀 설정 출력과 허가되지 않은 도구 실행을 거부한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **실패 격리(Failure Containment)**: 모델이 악성 지시를 따르더라도 비신뢰 입력을 민감정보 접근이나 상태 변경 권한과 분리하여 실제 피해로 확산하지 않게 하는 안전 설계 원칙.

</details>

- **실패 격리** 원칙에 따라 외부 자료는 비신뢰 문맥으로 분리하고 상태 변경 도구는 **PEP** 검증 및 **사용자 재승인** 후 실행 집행

#### 한줄 요약

- 프롬프트 인젝션은 완전 제거하기 어려우므로 비신뢰 입력을 격리하고 모델 실패가 실제 권한 오용으로 번지지 않게 설계해야 한다.
