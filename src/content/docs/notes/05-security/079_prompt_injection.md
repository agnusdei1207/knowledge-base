## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **프롬프트 인젝션**: 비신뢰 입력이 모델의 지침 해석을 교란하여 원래 규칙과 다른 출력이나 행동을 만들게 하는 공격이다.
- **인공지능(Artificial Intelligence, AI)**: 학습된 모델로 인식•추론•생성 작업을 수행하는 기술이다.
- **대규모 언어 모델(Large Language Model, LLM)**: 대규모 언어 데이터로 학습해 자연어를 이해•생성하는 모델이다.
- **지침•데이터 혼동**: 자연어로 함께 전달된 상위 지시와 비신뢰 자료를 모델이 구분하지 못하는 한계이다.

</details>

- 정의/개념: **AI** 시스템의 **LLM**이 비신뢰 입력을 지침으로 오인하게 하는 **프롬프트 인젝션** 공격이다.
- 배경/필요성: 자연어에서 **지침•데이터 혼동**을 완전히 제거하기 어렵다.

#### 한줄 요약

- 모델이 읽은 비신뢰 문장을 데이터가 아니라 새 명령으로 받아들여 원래 규칙과 다른 답이나 행동을 만드는 문제이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **직접 인젝션**: 공격 지시가 사용자의 대화 입력에 직접 포함되는 공격 경로이다.
- **간접 인젝션**: 공격 지시가 검색•웹•메일 같은 외부 자료를 통해 유입되는 경로이다.
- **검색 증강 생성(Retrieval-Augmented Generation, RAG)**: 외부 자료를 검색해 모델의 생성 문맥에 결합하는 방식이다.
- **피해 범위 제한**: 공격 문장 탐지에만 의존하지 않고 독립 정책•최소 권한으로 모델 실패가 실제 실행으로 이어지는 범위를 줄이는 원칙이다.

</details>

- **직접 인젝션**은 사용자 입력으로, **간접 인젝션**은 **RAG** 자료 등으로 비신뢰 지시가 유입된다.
- 두 경로 모두 프롬프트 은닉만으로 완전히 차단하기 어렵다.
- **피해 범위 제한**: 독립 정책•최소 권한으로 실행을 통제한다.

#### 한줄 요약

- 공격 문장을 모두 찾아내기 어려우므로 모델이 속아도 민감정보를 읽거나 중요한 도구를 바로 실행하지 못하게 해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **시스템 프롬프트**: 서비스가 모델에 제공하는 상위 지침과 행동 규칙이다.
- **사용자 프롬프트**: 사용자가 모델에 전달하는 요청과 대화 입력이다.
- **출처**: 외부 자료가 생성•수집된 위치와 신뢰 수준을 나타내는 정보이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: 모델 제안을 별도 규칙과 사용자 권한으로 검증•집행하는 경계이다.

</details>

```text
[프롬프트 인젝션 통제]
          |
          +-- [지침•입력 경계]
          +-- [외부 콘텐츠 처리]
          +-- [모델•문맥]
          +-- [응답•도구 제안]
          `-- [정책•권한 검증]
```

선의 의미: 입력 신뢰•모델 문맥•출력 제안•권한 집행의 정적 경계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 지침•입력 경계 | **시스템 프롬프트**•**사용자 프롬프트**와 자료 구분 |
| 외부 콘텐츠 처리 | **RAG**와 **출처** 정보로 신뢰 수준 표시 |
| 모델•문맥 | 응답•도구 호출 제안 생성 |
| 응답•도구 제안 | 구조화 출력•대상 정보 제공 |
| 정책•권한 검증 | **정책 집행점(PEP)**에서 실행 재검증 |

#### 한줄 요약

- 모델은 답과 행동을 제안할 뿐이며 별도 정책 경계가 실제 사용자 권한과 대상 자원을 확인한 뒤 실행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **사용자 재승인**: 고위험 행동의 대상•내용•영향을 보여 주고 실행 전에 다시 동의를 받는 통제이다.
- **거래 결속**: 사용자가 승인한 매개변수를 실제 실행 요청과 변경 불가능하게 묶는 통제이다.
- **샌드박스**: 도구의 파일•네트워크•실행 권한을 격리한 제한 환경이다.
- **단명 자격**: 하나의 작업과 짧은 시간에만 유효한 최소 권한 인증 정보이다.
- **시스템•사용자 문맥 결합**: 신뢰 수준이 다른 시스템 지침과 사용자 입력을 하나의 모델 문맥으로 구성하는 단계이다.
- **지침•비신뢰 데이터 혼동**: 모델이 사용자 입력이나 외부 자료를 실행 지침으로 오인하는 단계이다.
- **공격 지시 우선 해석**: 모델이 원래 정책보다 주입된 지시를 우선해 출력•행동 후보를 만드는 단계이다.
- **독립 권한•내용 검증 누락**: 모델의 행동 제안을 별도 실행 정책으로 재검증하지 않는 단계이다.
- **비승인 정보 접근•상태 변경**: 과도한 도구 권한으로 허가되지 않은 조회나 변경이 발생하는 단계이다.

</details>

```text
[상위 지침 무시•도구 실행 입력]
          |
          v
1. 시스템•사용자 문맥 결합
          |
          v
2. 지침•비신뢰 데이터 혼동
          |
          v
3. 공격 지시 우선 해석
          |
          `-- 응답•도구 제안
                    |
                    v
[정책 집행점(PEP)]
          |
          v
4. 독립 권한•내용 검증 누락
          |
          `-- 과도한 권한 도구 호출
                    |
                    v
5. 비승인 정보 접근•상태 변경
          |
          v
[조작된 응답•행동 결과]
```

### 동작 원리

1. **시스템•사용자 문맥 결합**: 신뢰 수준이 다른 자연어를 함께 구성한다.
2. **지침•비신뢰 데이터 혼동**: 사용자 문장을 실행 지침으로 오인한다.
3. **공격 지시 우선 해석**: 원래 정책과 다른 출력•행동을 생성한다.
4. **독립 권한•내용 검증 누락**: 모델 제안을 실행 권한처럼 수용한다.
5. **비승인 정보 접근•상태 변경**: 과도한 도구 권한으로 피해 발생한다.


#### 한줄 요약

- 모델이 악성 지시를 따르더라도 **샌드박스**와 **단명 자격**으로 실행 범위를 줄이고 **거래 결속**과 **사용자 재승인**으로 허용된 행동만 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **탈옥**: 모델의 안전 거부 정책을 우회해 금지된 응답을 얻으려는 공격이다.

</details>

| 프롬프트 공격 유형 | 직접 인젝션 | 간접 인젝션 | 탈옥 |
|:---|:---|:---|:---|
| 적용 기준 | **직접 인젝션** | **간접 인젝션** | **탈옥** |
| 핵심 특징 | 사용자 지시 유입 | 외부 자료 지시 유입 | 안전 거부 정책 우회 |
| 한계 | 입력 필터를 피하는 변형 공격 반복 | 출처 확장•지연 발동 위험 | 정책 일관성 저하 가능 |

#### 한줄 요약

- 직접형은 사용자가 공격하고 간접형은 모델이 읽는 자료가 공격하며 탈옥은 주로 금지 응답의 거부 규칙을 우회한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **OWASP(Open Worldwide Application Security Project)**: 애플리케이션 보안 지침을 공개하는 비영리 프로젝트이다.
- **LLM01:2025**: 직접•간접 프롬프트 인젝션을 LLM 응용의 최우선 위험으로 분류하는 OWASP 항목이다.
- **ATLAS(Adversarial Threat Landscape for AI Systems)**: AI 시스템 공격 전술•기법을 분류하는 MITRE 지식베이스이다.
- **AML.T0051**: LLM 프롬프트 인젝션과 하위 기법을 식별하는 ATLAS 항목이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 위협 유형 누락으로 시험 범위 축소 | **OWASP** **LLM01:2025** 적용 | 직접•간접 공격 시나리오 확보 |
| 공격 기법 추적 단절로 대응 공유 곤란 | **ATLAS** **AML.T0051** 매핑 | 직접•간접 하위 기법 추적 |
| 모델 권한 오판 시 유출•변경 확산 | **PEP**와 **단명 자격** 적용 | 유출•변경 피해 범위 제한 |
| 고위험 외부 행동을 자동 승인할 위험 | **거래 결속**과 **사용자 재승인** 적용 | 승인 대상 불일치•무단 실행 방지 |

#### 한줄 요약

- 고객 챗봇이 이전 지시를 무시하라는 요청을 받아도 정책 집행점은 비밀 설정 출력과 허가되지 않은 도구 실행을 거부한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **실패 격리**: 모델이 악성 지시를 따르더라도 비신뢰 입력을 민감정보 접근이나 상태 변경 권한과 분리하여 실제 피해로 확산하지 않게 하는 설계이다.

</details>

- **실패 격리** 원칙에 따라 외부 자료는 비신뢰 문맥으로 분리하고 상태 변경 도구는 **PEP**의 검증과 **사용자 재승인** 뒤에 실행한다.

#### 한줄 요약

- 프롬프트 인젝션은 완전 제거하기 어려우므로 비신뢰 입력을 격리하고 모델 실패가 실제 권한 오용으로 번지지 않게 설계해야 한다.
