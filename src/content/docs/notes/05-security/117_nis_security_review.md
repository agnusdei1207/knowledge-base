## 미리 알고가기

- **국가정보원(National Intelligence Service, NIS)**: 국가 정보보안 지침을 수립하고 위임된 정보화사업의 보안 적합성을 검토하는 기관이다.
- **제안요청서(Request for Proposal, RFP)**: 발주할 사업의 기능·보안 요구사항과 평가·검증 기준을 명시한 문서이다.
- **인공지능(Artificial Intelligence, AI)**: 정보화사업에서 데이터를 학습하여 자동화된 판단·분석을 수행하는 기술이다.
- **보안성 검토(Security Review)**: 공공 정보화사업의 설계·발주 전 보안대책을 검토하는 절차
- **보안적합성 검증**: 공공기관이 도입하는 보안 제품과 구성이 요구사항에 맞는지 확인하는 절차
- **외부 연계**: 기관 시스템이 클라우드·협력기관·인터넷과 데이터를 주고받는 연결



## Ⅰ. 개요

- 정의/개념: 공공 정보화사업의 설계·발주 전 보안대책 검토 절차
- **배경/필요성**: 구축 후 점검만으로 설계·계약에 누락된 보안 요구 보완 곤란

### 쉽게 이해하기 (학습용)

- 시스템 설계 전에 발주 단계에서 보안 요구를 확인함

## Ⅱ. 특징

- 정보화사업 공고 전 보안대책을 검토한다.
- 흐름·망·인증·암호·공급망 대책을 확인한다.
- 국가 지침에 따른 검토 경로와 의견을 RFP·설계에 반영한다.

### 쉽게 이해하기 (학습용)

- 기관이 자체 검토할지 상급기관이나 국가정보원에 의뢰할지는 사업 유형과 위임 기준에 따름

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 사업 범위 | 목적·정보·기술과 검토 대상 여부 |
| 데이터 흐름 | 정보의 저장·처리·전송 및 외부 연계 |
| 망 구성 | 보안 영역·접점·클라우드 접근 경로 |
| 보안 대책 | 인증·암호·로그·개발·공급망·대응 |
| 조치 추적 | 의견을 RFP·설계·검수 항목에 연결 |

```text
[사업 계획·데이터 흐름] ─검토 자료─> [검토 기관]
          ↑                              │ 보완 의견
          └── RFP·설계·계약 반영 ───────┘
                         ↓
                    [구축·검수]
```

### 쉽게 이해하기 (학습용)

- 사업 구조와 정보 흐름을 보여 주고 받은 보완 의견을 발주·설계·검수까지 추적함

## Ⅳ. 원리 및 절차 흐름도

```text
대상·범위판단 → 구조·위험검토 → 보완요구결정 → 설계·RFP반영 → 이행·잔여위험확인
```

| 절차 | 설명 |
|:---|:---|
| 대상·범위 판단 | 위임 기준과 사업 구조로 검토 대상·경계를 확정함 |
| 구조·위험 검토 | 데이터 흐름·망 구성·보호 자산과 보안대책의 공백을 분석함 |
| 보완 요구 결정 | 위험과 법적 요구에 따라 설계·계약 보완사항을 확정함 |
| 설계·RFP 반영 | 보완 요구를 설계·제안요청서·검수 기준에 추적 연결함 |
| 이행·잔여위험 확인 | 구축 결과와 미해결 사항의 승인·후속조치를 확인함 |

> 요약: 검토 의견을 RFP·설계·계약까지 추적함

### 쉽게 이해하기 (학습용)

- 검토 의견을 받은 것으로 끝내지 않고 구축 결과가 의견대로 구현됐는지 확인해야 함

## Ⅴ. 공공 보안 검토 절차 비교

| 비교축 | 보안성 검토 | 보안적합성 검증 |
|:---|:---|:---|
| 적용 기준 | 공고 전 설계·RFP에 보안을 반영할 때 | 제품 적용·운용 전에 구성을 확인할 때 |
| 핵심 특징 | 사업 구조와 보안대책 사전 검토 | 도입 제품·버전·구성의 적합성 검증 |
| 한계 | 검토 의견이 계약·구축에 미반영 | 인증 제품의 설치 설정·버전 불일치 |

### 쉽게 이해하기 (학습용)

- 보안성 검토는 사업 설계, 보안적합성 검증은 실제 도입 제품의 안전성을 확인함

## Ⅵ. 실무 사례

1. 정보화 사업 발주 전 **전체 연계 구조의 보안성 검토**

### 쉽게 이해하기 (학습용)

- 여러 계약으로 나뉜 사업도 전체 시스템·데이터·외부 연계 구조를 기준으로 보안 요구를 검토하고 필요한 통제를 제안요청서와 검수 기준에 반영한다.

## Ⅶ. 결론

- 구축 후 보안 보완의 비용과 공백을 줄이기 위해 사업 범위·연계 구조·보호 자산·중요 변경·법적 요구를 검토하여, 발주 전 보안성 검토 결과를 설계와 검수까지 추적해야 한다.

### 쉽게 이해하기 (학습용)

- 발주 전에 위험을 찾아 계약에 넣어야 납품 뒤 보안 기능을 추가하는 비용과 공백을 줄일 수 있음
