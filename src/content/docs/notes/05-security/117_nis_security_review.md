## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **보안성 검토**: 국가•공공기관 정보화사업의 계획 단계에서 보안대책 적절성을 확인하는 사전 절차이다.
- **국가정보원(National Intelligence Service, NIS)**: 국가 정보보안 지침을 수립하는 기관이다.

</details>

- 정의/개념: 공공 정보화사업의 계획•설계 단계에서 **NIS** 지침에 따라 보안 요구와 보호대책을 확인하는 **보안성 검토**이다.
- 배경/필요성: 구축 후 검토로는 계약에 빠진 보안 요구의 이행과 비용을 통제하기 어렵다.

#### 한줄 요약

- 시스템 설계 전에 발주 단계에서 보안 요구를 확인하는 것이 핵심이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **제안요청서(Request for Proposal, RFP)**: 사업의 기능•보안 요구와 평가•검증 기준을 명시한 문서이다.

</details>

- 사업 공고 전 **RFP**에 설계•보안대책을 반영하는 것이 핵심이다.
- 데이터•망•인증•암호 위험을 사업 경계에 따라 검토한다.
- 검토 의견을 RFP•설계•검수까지 추적한다.

#### 한줄 요약

- 기관이 자체 검토할지 상급기관이나 국가정보원에 의뢰할지는 사업 유형과 위임 기준에 따름이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **검토 범위**: 사업 목적•데이터•네트워크•제품•연계 구조를 기준으로 정한 사전 검토 대상이다.
- **RFP 추적**: 검토 의견을 발주 요구와 설계•검수 결과까지 연결하는 활동이다.

</details>

```text
공공 정보화사업 보안성 검토
├─ 사업 범위 · 검토 대상
│  └─ 목적 · 정보 · 기술 · 위임 기준
├─ 데이터 · 외부 연계
│  └─ 저장 · 처리 · 전송 경로
├─ 망 · 클라우드 구성
│  └─ 보안영역 · 접점 · 접근 경로
├─ 보안대책 · 검토 의견
│  └─ 인증 · 암호 · 로그 · 공급망
└─ RFP · 설계 · 검수 추적
   └─ 요구사항 · 구축 결과
```

| 구성요소 | 책임 |
|:---|:---|
| 사업 범위•검토 대상 | **검토 범위**에 목적•정보•기술•위임 기준 포함 |
| 데이터•외부 연계 | 저장•처리•전송 경로 분석 |
| 망•클라우드 구성 | 보안영역•접점•접근 경로 확인 |
| 보안대책•검토 의견 | 인증•암호•로그•공급망 보완 |
| RFP•설계•검수 추적 | **RFP 추적**으로 요구와 구축 결과 연결 |

#### 한줄 요약

- 사업 구조와 정보 흐름을 보여 주고 받은 보완 의견을 발주•설계•검수까지 추적하는 것이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **검토 의견 반영**: 보안성 검토 결과를 조달•계약•구축•시험 조건으로 연결하는 활동이다.
- **사업 경계•위험•위임 근거 검토**: 사업 유형•경계•정보 흐름과 검토 주체를 확인하는 단계이다.
- **보안 보완 의견•요구 확정**: 망•자산•통제 공백에 대한 개선 요구를 정하는 단계이다.
- **RFP•계약 보안 조건 반영**: 확정된 보완사항을 발주 및 계약 기준에 포함하는 단계이다.
- **설계•구축•검수 증적 검증**: 보안 요구의 구현 결과와 잔여위험을 확인하는 단계이다.

</details>

```text
사업 구조 · 정보 흐름 · 위임 근거
               │
          보안성 검토 요청
               ▼
1. 사업 경계•위험•위임 근거 검토
               │
          검토 의견 반환
               ▼
2. 보안 보완 의견•요구 확정
               │
               ▼
3. RFP•계약 보안 조건 반영
               │
               ▼
4. 설계•구축•검수 증적 검증
               │
               ▼
          이행 증적 · 잔여위험
```

### 동작 원리

1. **사업 경계·위험·위임 근거 검토**: 유형·정보 흐름 확인
2. **보안 보완 의견·요구 확정**: 통제 공백·개선 요구 확정
3. **RFP·계약 보안 조건 반영**: 보완사항을 발주 기준에 반영
4. **설계·구축·검수 증적 검증**: 이행 결과·잔여위험 검증

#### 한줄 요약

- 검토 의견을 받은 것으로 끝내지 않고 구축 결과가 의견대로 구현됐는지 확인해야 한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **보안적합성 검증**: 도입 정보보호제품의 안전성과 실제 구성 적합성을 확인하는 절차이다.

</details>

| 공공 보안 절차 | 보안성 검토 | 보안적합성 검증 |
|:---|:---|:---|
| 적용 기준 | 공고 전 설계•RFP 보안 반영 | 운용 전 제품 구성 확인 |
| 핵심 특징 | **보안성 검토**로 사업 보안대책 확인 | **보안적합성 검증**으로 구성 적합성 확인 |
| 한계 | 계약•구축 미반영 위험 | 설정•버전 불일치 위험 |

#### 한줄 요약

- 보안성 검토는 사업 설계, 보안적합성 검증은 실제 도입 제품의 안전성을 확인하는 것이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **전자정부법 제56조**: 행정기관의 정보통신망 안전성 확보 근거이다.
- **전자정부법 시행령 제69조**: 사전 보안성 검토 절차의 근거이다.
- **국가 사이버보안 기본지침**: 보안성 검토 대상•절차•위임 기준을 정한 지침이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 법률상 보안대책 | **전자정부법 제56조** 적용 | 안전성 확인 근거 확보 |
| 사전 검토 요청 | **전자정부법 시행령 제69조** 준수 | 발주 전 위험 보완 |
| 대상•위임 절차 | **국가 사이버보안 기본지침** 적용 | 검토 경로 명확화 |

#### 한줄 요약

- 여러 계약으로 나뉜 사업도 전체 시스템•데이터•외부 연계 구조를 기준으로 보안 요구를 검토하고 필요한 통제를 제안요청서와 검수 기준에 반영한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **계약 전 반영**: 보안 요구를 사업 초기의 제안요청서•계약•시험 기준에 포함하는 원칙이다.

</details>

- **계약 전 반영** 원칙에 따라 설계•RFP는 보안성 검토, 제품•버전•구성은 보안적합성 검증을 수행한다.

#### 한줄 요약

- 발주 전에 위험을 찾아 계약에 넣어야 납품 뒤 보안 기능을 추가하는 비용과 공백을 줄일 수 있다.
