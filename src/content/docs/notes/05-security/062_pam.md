## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PAM (특권 접근 관리)**: 일반 직원이 아니라, 리눅스 `root`나 윈도우 `Administrator` 계정으로 서버를 씹고 뜯고 맛볼 수 있는 '슈퍼 관리자'들의 접속과 작업 세션을 통제/감시하는 시스템이다.
- **특권 계정 (Privileged Account)**: 시스템 설정, 서비스 제어, 보안 정책 변경 등 인프라의 생사여탈권을 쥐고 있는 최고 관리자 계정이다.

</details>

- 정의: 시스템 최고 관리자 계정의 자격 증명, 접속 경로, 작업 세션을 사전 승인 기반으로 중앙 통제 및 감사하는 보안 체계이다.
- 배경: `root`나 `admin` 계정의 패스워드를 직원들끼리 포스트잇으로 공유하다 보니, 누가 언제 들어와서 DB를 날려먹었는지 책임 추적이 불가능해지기 때문이다.

#### 한줄 요약

- 관리자한테 진짜 패스워드를 안 알려주고, PAM 서버가 중간에서 화면만 띄워준 다음 작업 내역을 싹 다 녹화하는 기술이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **세션 중계 (Session Proxy)**: 관리자한테 진짜 패스워드를 안 알려주고, "넌 내(PAM) 뒤에 숨어있어" 한 다음 PAM 서버가 타겟 서버에 대신 로그인해서 터미널 화면만 띄워주는 중계기다.
- **JIT (적시 최소 특권)**: "주말에 서버 패치해야 하니 토요일 2시부터 4시까지만 딱 권한 열어줘" 하고 결재 시점에만 임시 권한을 부여하는 기술이다.
- **지속 발견 (Continuous Discovery)**: 인프라 내에 몰래 파놓은 백도어 관리자 계정이나, 퇴사자가 만들어놓고 간 특권 계정을 자동 스캔하여 잡아내는 통제 기능이다.

</details>

- **비밀번호 원천 은폐**: 비밀 금고(Vault)와 세션 중계(Proxy)를 결합하여, 실제 관리자가 타겟 서버의 진짜 패스워드를 평생 아예 모르도록 차단한다.
- **JIT 임시 특권 발급**: 무제한 상시 권한을 전부 박탈하고, 작업 승인 시점에만 권한을 줬다가 작업 끝나면 칼같이 회수하는 적시 최소 특권(JIT)을 적용한다.
- **미관리 특권 계정 식별**: 지속 발견(Discovery) 엔진을 통해 인프라 전반에 흩어진 미관리 특권 계정이나 우회 접속 경로를 식별하여 중앙으로 종속시킨다.

#### 한줄 요약

- 진짜 패스워드는 금고에 가두고, 승인받을 때만 중계기로 열어주고, 몰래 파놓은 관리자 계정은 색출해 낸다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **비밀 회전 (Secret Rotation)**: 작업 끝나고 관리자가 로그아웃하면, PAM이 "수고했어" 하면서 그 타겟 서버의 `root` 패스워드를 해커가 못 쓰게 바로 복잡한 난수로 바꿔버리는 기술이다.
- **세션 증적 (Session Audit Log)**: 관리자가 서버에 붙어서 친 모든 리눅스 명령어 타이핑과 터미널 화면 움직임을 CCTV처럼 100% 녹화해서 보관하는 감사 증거다.

</details>

```text
[ 특권 접근 관리(PAM) 통제 구조 ]

[ 1. 요청 및 사전 결재 ] ── ("주말에 DB 패치 좀 하겠습니다. 부서장님 승인 부탁요")
      │
      ▼
[ 2. JIT 자격 / 비밀 금고 ] ── ("결재 떨어짐! 금고(Vault)에서 2시간짜리 임시 열쇠 발급함")
      │
      ▼
[ 3. 세션 중계 및 접속 ] ── ("진짜 비번은 내가 대신 칠 테니까, 넌 나(PAM)를 통해서 화면만 봐")
      │
      ▼
[ 4. 명령 통제 및 세션 기록 ] ── ("어디서 함부로 'rm -rf'를 쳐? 차단! 그리고 화면 다 녹화 중임")
      │
      ▼
[ 5. 권한 회수 및 비밀 회전 ] ── ("작업 끝! 임시 권한 뺏고 서버 비번 난수로 즉시 돌려버림")
```

| 구성요소 | 직관적 비교 책임 | 비고 |
|:---|:---|:---|
| **요청 / 사전 승인** | 작업의 타당성, 목적, 대상 서버, 사용 시간을 **사전에 부서장에게 결재받음** | Approval |
| **비밀 금고 (Vault)** | 최고 관리자 패스워드나 SSH 키를 고도로 암호화해서 가둬두고 **중앙에서 관리함** | Vault |
| **세션 중계 (Proxy)** | 관리자가 진짜 비번을 못 보게 **대신 접속해서 터미널을 안전하게 중계함** | Proxy |
| **명령 통제 / 세션 기록** | 'drop table' 같은 위험 명령어를 차단하고 **터미널 전체 화면을 CCTV처럼 녹화함** | Record |
| **권한 회수 / 비밀 회전** | 작업 세션 종료 즉시 권한을 뺏고 **타겟 서버 비밀번호를 새로운 난수로 재설정함** | Rotation |

#### 한줄 요약

- 결재받고 $\to$ PAM이 대신 비번 쳐주고 $\to$ 화면 싹 다 녹화하고 $\to$ 작업 끝나면 비번을 바꿔버리는 구조다.

### 동작 원리

1. 신원•승인 판정: 직무 분리(SoD) 원칙에 따라 특권 요청자와 승인자를 분리하여 사전 결재.
2. JIT 자격 생성: 승인된 범위와 제한된 유효기간(TTL) 내에서만 쓰이는 일회성 임시 자격을 발급.
3. 세션 결속(중계): 사용자가 패스워드를 보지 못하도록 PAM 게이트웨이가 타겟 시스템에 자격을 대신 주입.
4. 세션 기록 및 통제: 블랙리스트 기반 위험 명령 실행을 차단하고 작업 화면과 텍스트(키스트로크)를 실시간 녹화.
5. 권한 및 비밀 회전: 세션 종료 즉시 자격 증명을 폐기하고 타겟 서버의 마스터 패스워드를 난수로 회전(재설정).

#### 한줄 요약

- 결재 $\to$ 임시 권한 발급 $\to$ 비밀번호 은폐 중계 $\to$ 화면 녹화 및 명령 차단 $\to$ 비번 초기화 루틴이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 특권 관리 유형 | **공유 상시 계정 (기존 악습)** | **PAM (중앙 통제형)** | **비상 접근 (Break-Glass)** |
|:---|:---|:---|:---|
| 비유 및 핵심 특징 | **포스트잇에 적어놓고 전 직원이 다 돌려쓰는 마스터 키** | **결재받아야만 꺼내주고, 다 쓰면 비번 바꿔버리는 금고** | **새벽에 서버 터졌을 때 결재 없이 일단 깨고 들어가는 소화전 망치** |
| 핵심 특징 | `root` 패스워드를 팀원들끼리 **공유해서 상시로 무제한 접속함** | 비밀 금고, 세션 중계, 화면 녹화를 하나로 묶어 **특권 전주기를 통합 통제함** | 서버 장애 등 초비상 상황 시 사전 승인을 우회하되 **강력한 사후 감사를 강제함** |
| 장단점 / 한계 | 사고 터졌을 때 누가 그랬는지 **책임 추적이 절대 불가능함** | 관리자 권한 남용을 완벽 차단하지만 **중계 서버(PAM)가 죽으면 작업이 올스톱 남** | 승인 절차가 생략되어 빠른 장애 복구가 가능하나 **악용 시 파급력이 큼** |

#### 한줄 요약

- 평소엔 **공유 계정** 폐지하고 깐깐한 **PAM** 쓰다가, 새벽에 불나면 사후 보고를 조건으로 **비상 접근** 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **명령 통제 (Command Control)**: PAM 서버가 터미널 명령어 라인을 실시간으로 감시하다가, 블랙리스트에 등록된 `rm -rf` 나 `drop database` 같은 재앙급 명령어가 감지되면 엔터 치는 순간 세션을 끊어버리는 기술이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 관리자가 화나서 **DB 서버 통째로 날려버리고 퇴사 인증함** | 최고 관리자(root) 권한으로 접속하면 파괴적인 위험 명령어(rm, drop)를 막을 시스템적 통제가 없음 | PAM 중계 서버 단에서 블랙리스트 기반의 실시간 **위험 명령어 통제(Command Control) 강제** | 홧김에 치는 시스템 파괴 명령어 및 치명적 설정 변경 원천 원천 차단 |
| 서버 털렸는데 **해커가 관리자 비번으로 들어와서 CCTV(로그) 싹 다 지움** | OS 자체에 남는 시스템 로그만 믿다가, 해커가 root 권한으로 접속해 로그 파일까지 싹 다 날려먹음 | OS 밖의 안전한 PAM 서버에 텍스트 로그와 **작업 화면 전체를 동영상으로 녹화 보존** | 로그 삭제/위변조 공격 무력화 및 법적 증거 수준의 사후 추적성 확보 |
| PAM 서버 구축해 놨더니 **직원들이 꼼수로 타겟 서버에 직접 붙어서 작업함** | 타겟 서버(리눅스, 윈도우)의 방화벽이 허술해서 PAM을 안 거치고 다이렉트로 접속이 가능함 | 타겟 시스템의 OS 방화벽에서 관리자 포트(SSH/RDP)는 **오직 PAM 서버 IP만 전면 허용** (직접 접속 차단) | PAM 통제 우회 시도 원천 차단 및 모든 관리자 작업의 100% 가시성 확보 |

#### 한줄 요약

- 위험 명령어는 즉시 자르고, OS 로그 대신 PAM에 화면 녹화 남기고, 직접 접속(우회)은 방화벽으로 막아라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **특권 책임 추적성 (Privileged Account Traceability)**: `root` 계정으로 사고가 터졌을 때, "이거 홍길동 대리가 밤 11시에 접속해서 drop 친 거다"라고 1:1로 범인을 특정하고 법적/감사적 증거를 입증할 수 있는 핵심 보안 성질이다.

</details>

- 시스템 인프라의 생명줄을 쥐고 있는 특권 계정 관리는, 비밀번호 직접 공유를 전면 폐지하고 **비밀 금고**와 **세션 중계**를 결합한 **PAM** 아키텍처를 도입하여 모든 작업 화면을 녹화하고, **JIT 최소 특권**과 **비밀 회전**을 통해 **특권 책임 추적성**을 100% 확보하는 실무 기조를 확립함

#### 한줄 요약

- `root` 비번 공유 금지하고, **PAM 중계/화면 녹화**와 **비밀번호 자동 회전**으로 책임 추적성 보장해라.
