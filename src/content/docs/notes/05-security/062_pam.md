## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PAM(Privileged Access Management, 특권 접근 관리)**: 기업의 인프라(서버, 네트워크, DB, 클라우드 콘솔)에 대해 무제한 제어 권한을 가진 최고 관리자 계정(`root`, `Administrator`, `AWS root/IAM Admin`)의 자격증명을 비밀 금고(Vault)에 격리 보관하고, 사전 승인 기반의 적시 권한 부여(JIT)와 세션 프록시 중계를 통해 실시간 명령어 통제 및 세션 전체를 녹화 감사하는 특권 통제 솔루션.
- **공유 관리자 계정의 책임성 상실(Lack of Accountability Defect)**: 여러 엔지니어가 단일 `root` 계정의 고정 패스워드를 공유하여 작업할 경우, 침해사고나 파괴적 명령어 실행 시 실제 행위 주체를 식별할 수 없는 보안 감사의 근본 결함.

</details>

- 정의/개념: 상시 특권(Standing Privileges)을 박탈하고 **비밀 금고(Vault) 패스워드 은닉 $\rightarrow$ 사전 결재 기반 JIT(Just-In-Time) 권한 부여 $\rightarrow$ 세션 프록시 중계 및 자격증명 자동 주입 $\rightarrow$ 실시간 위험 명령어 차단 및 비디오 녹화 $\rightarrow$ 세션 종료 즉시 패스워드 일회용 난수 회전(Rotation)** 을 집행하는 **특권 계정 제로 트러스트 아키텍처**
- 배경/필요성: 공유되는 상시 관리자 패스워드는 유효 기간이 사실상 무한해 단 한 번의 유출이 전 인프라 장악과 횡적 이동으로 직결되고 행위 주체도 특정되지 않으므로, 관리자와 타깃 서버 사이에 자격증명을 대신 보관·주입하고 세션을 중계하는 프록시 계층을 끼워 권한의 수명을 승인된 작업 시간으로, 패스워드의 수명을 1회로 줄일 요구

#### 한줄 요약
- PAM의 요체는 관리자를 불신하는 데 있지 않고 자격증명의 유효 기간을 작업 단위로 잘라 유출되더라도 재사용할 가치가 남지 않게 만드는 데 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **적시 권한 부여(Just-In-Time Privilege, JIT)**: 관리자에게 24시간 상시 권한을 부여하지 않고, 작업 계획서 승인 시점에 한하여 1~2시간 단위의 시한부(TTL) 임시 권한을 발급한 후 작업 완료 시 즉시 권한을 자동 박탈하는 원칙.
- **자격증명 회전(Credential Rotation)**: 관리자가 PAM 프록시를 통해 타깃 서버 작업을 완료하고 로그아웃하는 즉시, 타깃 서버의 실제 `root` 패스워드를 128비트 암호학적 난수로 자동 변경하여 이전 세션 자격증명의 재사용을 원천 차단하는 기술.

</details>

- **자격증명 무노출 원칙 (Zero Password Exposure)**: 관리자는 타깃 서버의 실제 패스워드를 평생 알지 못하며 PAM 프록시가 세션 연결 시 자격증명을 백그라운드 주입
- **불변 세션 감사 증적 (WORM Session Recording)**: 터미널 키스트로크(타이핑 텍스트) 로그와 그래픽 화면 전체를 동영상으로 녹화하여 타깃 OS 외부 불변 스토리지에 보존
- **비인가 직접 접속 원천 차단**: 타깃 서버 방화벽(Security Group)에서 관리 포트(SSH 22, RDP 3389) 인바운드를 오직 PAM 프록시 IP로만 엄격 격리

#### 한줄 요약
- 네 특징은 모두 관리자의 즉시 접속 편의를 사전 승인 대기와 프록시 경유라는 지연으로 맞바꾼 대가로 얻어진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **PAM 5대 핵심 아키텍처 모듈**:
  1. **Enterprise Vault (비밀 금고)**: 최고 관리자 패스워드/SSH Key를 HSM 기반으로 암호화 저장.
  2. **Session Proxy (세션 중계 게이트웨이)**: SSH/RDP 프로토콜을 인터셉트하여 터미널 중계 및 명령 필터링.
  3. **JIT Policy Engine**: 작업 승인 티켓(ITSM/Jira)과 연동하여 임시 자격을 프로비저닝.
  4. **Command Filter Engine**: `rm -rf`, `DROP DATABASE` 등 블랙리스트 명령어 실시간 인라인 드롭.
  5. **Credential Rotator**: 세션 종료 및 주기적 스케줄에 따라 타깃 시스템 패스워드 재설정.

</details>

```text
[ 시스템 엔지니어 (개인 계정으로 PAM 포털 로그인 / MFA) ]
                           │ (1. 작업 신청 및 사전 승인 획득)
                           ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. PAM 중앙 제어 서버 (Enterprise Vault & JIT Engine) ]              │
│  ├─ 비밀 금고(Vault): 타깃 서버 `root` 패스워드를 HSM으로 암호화 관리    │
│  └─ JIT 엔진: 2시간 유효 임시 세션 토큰 생성 ➔ [ 세션 프록시로 권한 위임]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (2. 세션 중계 및 자동 자격증명 주입)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. PAM 세션 프록시 게이트웨이 (Session Proxy & Gateway) ]             │
│  ├─ 관리자에게 패스워드 미노출 (프록시가 타깃 서버에 root 자격 자동 주입) │
│  ├─ 키스트로크 및 RDP 그래픽 화면 실시간 비디오 녹화 (외부 스토리지 전송)│
│  └─ 명령 필터링: `rm -rf /` 입력 감지 시 ➔ [ 세션 즉시 강제 종료(Kill) ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (3. 격리된 인바운드 SSH/RDP 연결)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 타깃 인프라 계층 (Target Infrastructure: Linux / Windows / DB) ]   │
│  └─ 방화벽 통제: 관리자 포트(22, 3389) 인바운드는 오직 PAM 프록시만 허용│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (4. 작업 종료 및 로그아웃 이벤트)
                                     ▼
[ Credential Rotator ➔ 타깃 서버의 실제 `root` 패스워드를 신규 난수로 즉시 재설정 ]
```

선의 의미: 관리자가 승인을 받아 PAM 프록시를 통해 타깃 서버에 접속하고, 명령 통제 및 화면 녹화를 거쳐 세션 종료 즉시 패스워드가 회전되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **Enterprise Vault (비밀 금고)** | 모든 서버, DB, 클라우드 루트 계정의 패스워드/SSH Key를 중앙 암호화 저장 | Password Vault |
| **Session Proxy (세션 게이트웨이)**| SSH/RDP 세션을 가로채어 자격증명 주입, 터미널 화면 녹화 및 명령 필터링 | Bastion Gateway|
| **JIT 권한 부여 모듈** | 무제한 상시 특권을 배제하고 승인된 티켓 기반으로 최소 시간 권한만 활성화 | Just-In-Time |
| **명령 통제 엔진 (Command Control)**| 실시간 키보드 입력 스트림을 분석하여 파괴적 위험 명령어 실행 차단 | Command Filter |
| **Credential Rotator (비밀 회전기)**| 세션 종료 즉시 또는 정기 스케줄에 따라 타깃 시스템의 패스워드를 자동 변경 | Auto-Rotation |

#### 한줄 요약
- 자격증명이 금고로 옮겨간 순간 세션 프록시가 인프라로 향하는 유일한 접속 경로가 되므로, 프록시의 가용성이 곧 운영 작업 전체의 가용성이 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **PAM 특권 세션 5단계 수명주기**:
  1. 관리자 작업 신청 및 부서장 사전 승인
  2. JIT 임시 자격 활성화 및 세션 프록시 라우팅
  3. 자격증명 자동 주입 및 격리 터미널 연결
  4. 세션 비디오 녹화 및 실시간 위험 명령어 필터링
  5. 세션 종료, 권한 회수 및 패스워드 즉시 난수 회전

</details>

```text
1. [작업 신청 및 승인] 관리자가 ITSM에 "결제 DB 패치" 작업 신청 ➔ 부서장이 대상 서버 및 2시간 작업 승인
            │
            ▼
2. [JIT 세션 기동] PAM 서버가 금고(Vault)에서 해당 DB 서버의 자격증명을 인출하고 임시 프록시 세션 생성
            │
            ▼
3. [자격증명 무노출 중계] 관리자가 PAM 웹 콘솔에서 "접속" 클릭 ➔ 프록시가 타깃 서버에 `root` 자격을 자동 주입하여 터미널 연결
            │
            ▼
4. [실시간 감시 및 명령 통제]
    ├─ 관리자의 모든 키스트로크 및 화면 렌더링을 불변 감사 서버에 비디오로 실시간 저장
    └─ `DROP TABLE` 등 위험 명령어 입력 감지 시 ➔ [명령어 즉시 드롭 및 관리자 세션 강제 차단]
            │
            ▼
5. [세션 종료 및 비밀번호 회전]
    ├─ 작업 완료 후 로그아웃 ➔ PAM이 JIT 임시 권한 즉시 폐기
    └─ Credential Rotator가 타깃 서버에 접속하여 실제 `root` 패스워드를 128비트 난수로 즉시 변경(Rotation)
```

**동작 원리**

1. **승인 없는 특권 접근 원천 봉쇄**: 티켓팅 시스템과 결합하여 미승인 접속 시도 사전 차단
2. **신뢰 경계 물리적 분리**: 관리자 PC가 타깃 서버와 직접 통신하지 않고 오직 PAM 프록시와만 통신
3. **인라인 패킷 인스펙션**: 터미널 프로토콜 내부의 텍스트 스트림을 실시간 분석하여 파괴적 행위 중단
4. **증적 위변조 차단**: 타깃 서버가 침해당하더라도 감사 로그는 별도의 PAM WORM 스토리지에 보존되어 안전
5. **자격증명 수명 축소**: 단 1회성(One-Time)으로 사용된 비밀번호를 즉시 변경하여 탈취 위험성 완전 소멸

#### 한줄 요약
- 승인·중계·회전 중 하나만 빠져도 통제가 무너지며, 특히 회전이 없으면 세션 동안 타깃에 주입된 자격증명이 통제 밖에서 그대로 재사용된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **특권 관리 3대 방식 비교**: 공유 계정 상시 사용(레거시), PAM 중앙 통제, 비상 접근(Break-Glass)의 비교.

</details>

| 비교 항목 | 공유 상시 계정 (Legacy) | PAM 중앙 통제 (JIT Proxy) | 비상 접근 (Break-Glass / Firecall) |
|:---|:---|:---|:---|
| **패스워드 관리** | 포스트잇/파일로 엔지니어 간 공유 | **비밀 금고(Vault) 격리 및 자동 회전** | **물리적 금고/HSM 봉인 보관 (비상 시 해제)**|
| **접속 방식** | 관리자가 타깃 서버에 직접 SSH/RDP | **PAM 세션 프록시 게이트웨이 중계** | 비상 전용 콘솔을 통한 직접 접속 (사후 감사)|
| **권한 유효 기간** | **영구적 상시 권한 (Standing Privilege)**| **작업 시간 한정 JIT 시한부(1~2시간)** | 장애 복구 시까지 한시적 사용 |
| **감사 및 추적성** | **전혀 불가 (공용 root 사용으로 식별 불가)**| **개인별 키스트로크 및 화면 100% 녹화** | **비상 기동 전후 집중 감사 및 사후 소명** |
| **보안 사고 위험도**| **최상 (패스워드 유출 시 전 인프라 장악)** | **극히 낮음 (제로 트러스트 최소 특권 달성)**| 보통 (엄격한 사후 감사로 남용 방지) |

#### 한줄 요약
- 공유 상시 계정은 통제 불가 위험, PAM은 JIT 기반 제로 트러스트 표준, 비상 접근은 긴급 장애 복구용이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Break-Glass (비상 탈출 계정)**: PAM 서버 전체 다운이나 네트워크 고립 장애 발생 시, 미션 크리티컬 시스템 복구를 위해 사전 승인을 우회하여 즉각 로그인할 수 있도록 물리적으로 분리 보관되는 비상 관리자 자격증명.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 관리자가 타깃 서버 OS에서 파괴적인 명령어(`rm -rf`, `DROP DATABASE`)를 **실행하여 발생하는 대규모 데이터 유실 장애** | **PAM 세션 프록시 단에서 정규식 기반 위험 명령어 실시간 차단(Command Control) 및 세션 즉각 사살** | 관리자의 실수 또는 악의적 파괴 명령어 실행 100% 선제 원천 차단 |
| 침해사고 발생 시 타깃 서버의 로컬 감사 로그가 **root 권한 탈취자에 의해 완전히 삭제되어 원인 규명 불가** | **OS 외부 격리된 PAM 저장소에 모든 터미널 키스트로크 및 그래픽 화면을 WORM 비디오로 실시간 저장** | 감사 로그 위변조/삭제 공격 무력화 및 법적 효력을 갖는 완벽한 포렌식 증적 확보 |
| 엔지니어가 PAM 프록시를 우회하여 **타깃 서버에 직접 SSH/RDP로 접속하는 보안 사각지대 발생** | **타깃 서버 OS 방화벽 및 클라우드 보안그룹에서 관리 포트 인바운드를 PAM 프록시 IP로만 독점 허용** | PAM 통제 우회 경로 100% 원천 차단 및 모든 관리자 작업의 전수 가시성 확보 |

#### 한줄 요약
- 세 대책은 PAM 장애 시 관리자가 직접 접속할 길까지 함께 막으므로, 그 대가로 물리 격리된 **Break-Glass** 자격증명 절차를 반드시 별도로 설계해야 한다.

## Ⅶ. 결론

- 상시 권한은 금고에 격리하고 작업 위험에 따라 **JIT 권한**과 세션 통제 적용

#### 한줄 요약
- PAM은 특권을 없애는 선택이 아니라 특권이 존재하는 시간을 승인된 작업 구간으로 한정하는 선택이며, 그 구간 밖에서 일어난 자격증명 유출은 무의미해진다.
