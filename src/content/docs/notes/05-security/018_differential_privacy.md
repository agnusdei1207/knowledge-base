## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **차등 프라이버시 (DP)**: 전체 통계 데이터에 고의로 가짜 먼지(노이즈)를 섞어서, 전체 흐름은 맞추면서도 "특정 개인이 이 통계에 들어있는지"는 절대 모르게 숨기는 수학 모델이다.
- **인접 데이터셋**: 내 데이터가 '들어있는' 100만 명 DB와 '빠져있는' 99만 9,999명 DB. 이 두 DB를 비교해서 내 정보가 침해당하는지 수학적으로 체크하는 기준점이다.

</details>

- 정의: 인접 데이터셋 간의 결괏값 차이를 수학적 확률(ε, δ)로 철저히 통제하여, 특정 개인의 포함 여부를 절대 역추론할 수 없게 막는 기술이다.
- 배경: 이름, 민번만 가리는 기존 '정적 익명화'는 데이터를 다른 곳과 결합하거나 계속해서 질문을 던지면 결국 특정 개인이 식별되는 치명적 한계가 터졌기 때문이다.

#### 한줄 요약

- 통계 결과에 고의로 '먼지(노이즈)'를 섞어서, 숲(전체 통계)은 보이지만 나무(개인)는 절대 식별하지 못하게 만드는 마법이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **프라이버시 예산 (ε, Epsilon)**: 먼지(노이즈)를 얼마나 빡세게 뿌릴지 정하는 조미료 양이다. 예산(ε)이 0에 가까울수록 철통방어가 되지만 통계 정확도는 쓰레기가 된다.
- **후처리 불변성**: 한 번 노이즈(DP)를 섞어놓은 데이터는 지지고 볶고 AI에 넣고 돌려도, 절대 원래의 개인정보로 되돌아가지 않는 특성이다.

</details>

![프라이버시 예산이 작아질수록 증가하는 노이즈 척도](/study/diagrams/differential-privacy-noise.svg)

> 요약: **프라이버시 예산 ε** 작을수록 노이즈 주입량이 증가하고 프라이버시 보장 강도가 강력해짐

- **밸런스 게임 (Trade-off)**: 예산(ε)을 짜게 주면 프라이버시 강도는 올라가지만 데이터가 뭉개지고, 넉넉히 주면 정확도는 오르지만 털릴 위험이 커진다.
- **기여 한도 (Contribution Bound)**: 한 놈의 튀는 데이터가 통계 전체를 휘젓지 못하도록, 단일 개인의 영향력을 제한한다.
- **결과 보장 (후처리 불변성)**: 생성된 결과물에 어떤 추가 연산을 가해도, 처음에 보장된 프라이버시 수준이 수학적으로 절대 떨어지지 않는다.

#### 한줄 요약

- 보안과 정확도 사이에서 예산(ε)으로 줄타기를 하며, 한 번 노이즈를 섞으면 영원히 원천 보호가 유지된다(후처리 불변성).

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **민감도 (Sensitivity)**: 내 데이터 하나가 빠졌다고 전체 평균이 확 바뀌면 민감도가 높은 거다. 이 민감도에 맞춰서 노이즈를 얼마나 뿌릴지 결정한다.
- **프라이버시 회계 (Privacy Accountant)**: "질문 1번에 예산 0.1 소진!" 하면서, 정해진 프라이버시 예산(ε)이 다 떨어지면 시스템을 셧다운시키는 장부다.

</details>

```text
[ 차등 프라이버시 노이즈 주입 구조 ]

[ 1. 보호 단위 및 민감도 산정 ] ── (내 데이터 1개가 전체 통계에 얼마나 영향을 주는지 계산함)
      │
      ▼
[ 2. 프라이버시 예산 (ε, δ) 설정 ] ── ("이번 프로젝트에 허용된 총 예산은 1.0이야" 하고 세팅함)
      │
      ▼
[ 3. 노이즈 메커니즘 (라플라스 등) ] ── (민감도와 예산에 맞춰서 가짜 데이터(노이즈)를 섞음)
      │
      ▼
[ 4. 프라이버시 회계 (장부 작성) ] ── (질문 한 번 할 때마다 예산 차감하고 잔고 0 되면 원천 차단함)
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **보호 단위 및 민감도** | 내 데이터 1개가 빠졌을 때 **통곗값이 얼마나 튀는지 계산함** | Sensitivity |
| **프라이버시 예산 (ε, δ)** | 프라이버시 방어력과 정확도 사이의 **줄타기 상한선(Trade-off)을 정함** | Budget |
| **노이즈 메커니즘** | 산정된 민감도에 비례해서 **수학적인 가짜 먼지(Laplace/Gaussian)를 뿌림** | Noise |
| **프라이버시 회계** | 예산이 바닥나서 데이터가 침해당하기 전에 **질문을 원천 차단하는 장부** | Accountant |

#### 한줄 요약

- 예산 잡고 $\to$ 튀는 값(민감도) 계산해서 $\to$ 그만큼 노이즈 뿌리고 $\to$ 침해당하기 전에 장부 닫고 질문을 막는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **노이즈 주입 (Noise Injection)**: 라플라스(Laplace) 같은 수학 공식을 써서, 원래 통계 결과에 미세한 가짜 먼지(+1, -2 등)를 더해버리는 과정이다.

</details>

```text
[ 차등 프라이버시 예산 차감 및 공개 흐름 ]

┌──────────────────────────────┐
│ 1. [사용자 질의 및 민감도 산정]
│ ("강남구 30대 평균 연봉 알려줘" -> "이거 한 명 빠지면 얼마나 변하지?" 계산)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [누적 프라이버시 예산 확인 (장부 검사)]
│ (장부를 보고 "너 예산 남았냐?" 확인. 다 썼으면 여기서 바로 원천 차단됨)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [노이즈 스케일 산정 및 주입]
│ (민감도와 예산에 맞춰서 라플라스 먼지(노이즈)를 연봉 결과에 섞음)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [예산 차감 및 통계 공개]
│ (장부에서 예산 깎고, 먼지가 섞인 '안전한' 통곗값을 사용자에게 던져줌)
└──────────────────────────────┘
```

### 동작 원리

1. 기여 한도 및 민감도 산정: 개인별 최대 영향 한도를 제한하고 질의 민감도를 산정함.
2. 예산 확인: 프라이버시 회계를 대조해 누적 예산 잔여량을 철저한 검증함.
3. 노이즈 승인 및 주입: 노이즈 스케일을 정하고 라플라스/가우시안 노이즈를 결과에 가산함.
4. 예산 차감: 사용된 프라이버시 예산을 장부(회계)에서 차감하고 결과를 반환함.

#### 한줄 요약

- 질문 받으면 $\to$ 예산 남았나 확인하고 $\to$ 노이즈 섞어서 결과 주고 $\to$ 장부에서 깎는다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙 DP (Central DP)**: 진짜 원본 데이터를 중앙 서버에 싹 다 모은 다음에, 서버가 통계 낼 때 노이즈를 섞는 방식이다.
- **로컬 DP (Local DP)**: 폰(단말기)에서 데이터를 보낼 때부터, 아예 내 폰에서 노이즈를 섞어서 서버로 보내는 방식이다. (구글, 애플이 쓰는 방식)

</details>

| 차등 프라이버시 방식 | **중앙 DP (서버가 섞음)** | **로컬 DP (내 폰에서 섞음)** | **셔플 DP (중간자 혼합)** |
|:---|:---|:---|:---|
| 핵심 특징 | **선생님이 걷어가서 가짜 섞음** | **내가 가짜 써서 선생님한테 냄** | **가면 쓴 중간자가 카드 섞어줌** |
| 핵심 기술 원리 | 원본 데이터를 중앙(서버)에 모아둔 뒤, 통계를 낼 때 **서버가 직접 노이즈를 뿌림** | 단말기(클라이언트)가 서버로 데이터를 쏘기 전에 **기기에서 미리 노이즈를 섞음** | 익명 셔플러 서버가 데이터 전송 순서를 무작위로 섞어 **누가 보낸 건지 모르게 함** |
| 적용(최고 장점) | 통계 정확도가 높아서 **정밀한 데이터 분석이나 내부 AI 학습에 유리함** | 구글/애플 같은 **서버조차 못 믿을 때 내 데이터를 완벽히 방어함** | 로컬 DP의 '정확도 급격한 저하'을 막고, 중앙 DP의 '서버 해킹' 위험을 **보완함** |
| 치명적 한계 | 노이즈 뿌리기 전 원본이 모여 있는 **중앙 서버 자체가 침해당하면 게임 끝임** | 각자 노이즈를 너무 많이 섞어서 **전체 통계 정확도가 쓰레기가 됨** | 중간에 껴있는 **셔플러 서버 자체가 해킹당할 위험성이 존재함** |

#### 한줄 요약

- 정확도가 생명이면 서버가 섞는 '중앙 DP', 서버조차 못 믿겠으면 내 폰에서 섞는 '로컬 DP'를 쓴다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **DP-SGD**: AI(딥러닝)가 데이터를 너무 똑똑하게 '암기'해버려서 나중에 "너 그 데이터 썼지?" 하고 침해당하는 걸 막으려고, AI 학습 과정에 노이즈를 섞는 기술이다.
- **기울기 클리핑 (Gradient Clipping)**: 튀는 데이터 하나가 AI 모델 전체를 휘젓지 못하게, 데이터의 영향력(기울기) 한도를 가위로 싹둑 잘라버리는 거다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 꼼수로 질문을 반복해서 **결국 특정 개인 원본을 역추론함** | 통계에 계속 접근하면 노이즈가 상쇄되어 원본이 드러나는 수학적 한계가 존재함 | 전체 **'프라이버시 예산(ε)' 한도를 정하고, 소진 시 추가 질의를 무조건 셧다운** | 무한 질의를 통한 Differential 추론 공격 방어 및 데이터 수명 통제 |
| 극단적인 이상치 1개 때문에 **통계 결과가 급격히 요동침** | 민감도가 너무 크면 덮어야 할 노이즈도 급격히 커져서 데이터가 쓰레기가 됨 | 특정 데이터의 최대 영향력을 제한하는 **'기여 한도 제한(Clipping)' 강제 적용** | 이상치로 인한 민감도 폭증 억제 및 노이즈 주입량 통제 (정확도 철저한 방어) |
| AI가 내 의료 기록을 다 암기했다가 **나중에 똑같이 뱉어냄** | 딥러닝 모델이 학습용 원본 데이터를 과적합(Overfitting)하여 기억해 버림 | 모델 학습(역전파) 시 노이즈 주입하고 가위질하는 **'DP-SGD 및 기울기 클리핑' 적용** | AI 모델의 개별 표본 암기(Membership Inference) 및 원본 유출 공격 원천 차단 |

#### 한줄 요약

- 예산 다 쓰면 차단하고, 튀는 놈은 가위로 자르고(Clipping), AI 학습할 때도 노이즈(DP-SGD)를 부어라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 데이터 수집자의 신뢰도에 따라 **중앙 DP / 로컬 DP** 활용 선택하고, 통계 유용성과 보호 강도(Trade-off)를 조절하는 **프라이버시 예산(ε)** 및 AI 딥러닝 유출 방지를 위한 **DP-SGD** 적용 기조를 확립함

#### 한줄 요약

- AI 시대의 데이터 유출을 막는 수학적 방패다. 의도된 먼지(노이즈)를 섞어 나무는 숨기고 숲만 보여준다.
