## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Differential Privacy (차등 프라이버시, DP)**: 데이터셋에 특정 개인의 포함 여부와 무관하게 연산 결과의 확률 분포가 오차($e^\epsilon$) 내에서 동일함을 수학적으로 보증하는 기술.
- **Neighboring Datasets ($D, D'$)**: 단 1개의 레코드 차이만 존재하는 두 데이터베이스.

</details>

- 정의/개념: 인접 데이터셋($D, D'$)에 대해 **개인 레코드의 포함 여부와 무관하게 연산 결과 분포가 $e^\epsilon$ 내에서 동일하도록 수학적 노이즈를 주입하는 비식별화 기술**
- 배경/필요성: 기존 휴리스틱 가명화 조치의 **외부 데이터 결합 재식별(Linkage Attack) 취약성, 반복 차분 질의를 통한 개인정보 역추론 방어 불가**

#### 한줄 요약
- 수학적 노이즈 주입을 통해 개별 데이터의 존재 여부를 감추고 전체 통계적 유용성을 보존한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **Privacy Budget ($\epsilon$, 엡실론)**: 허용 가능한 프라이버시 손실 상한선으로, $\epsilon$이 작을수록 노이즈가 커져 보안이 강화되고 $\epsilon$이 클수록 분석 정확도가 높아짐.
- **Global Sensitivity ($\Delta f$, 전역 민감도)**: 임의의 두 인접 데이터셋 간에 함수 $f$의 출력값이 변할 수 있는 최대 차이($\max \|f(D) - f(D')\|$).

</details>

- **수학적으로 증명 가능한 강력한 안전성**: 배경지식의 수준과 무관하게 **공격자의 결합 재식별 확률을 수학적 상한($e^\epsilon$)으로 완벽 제어**
- **사후 처리 불변성(Post-Processing Invariance)**: 노이즈가 적용된 통계값에 **어떠한 사후 연산이나 AI 모델링을 가해도 프라이버시 손실 불변**
- **조합성(Composability)을 통한 누적 손실 통제**: 연속적인 다중 질의 시 **프라이버시 예산 합산($\sum \epsilon_i$)으로 총 정보 유출량 엄격 관리**

#### 한줄 요약
- 수학적 안전성 보증, 사후 처리 불변성, 조합성 기반 누적 손실 통제를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Privacy Accountant (프라이버시 회계사)**: 다중 쿼리나 AI 학습 스텝마다 소진되는 누적 프라이버시 손실을 추적하고 예산 초과 시 질의를 차단하는 관리자.

</details>

```text
[중앙형 차등 프라이버시 질의 및 노이즈 주입 아키텍처]
|-- Raw Database (원본 데이터셋 D) -> True Query Result: y = f(D)
`-- Differential Privacy Engine
    |-- 1. Sensitivity Analyzer (전역 민감도 Delta f = max |f(D) - f(D')| 산정)
    |-- 2. Privacy Accountant (예산 잔여량 eps_total - sum(eps_i) 추적 및 초과 차단)
    `-- 3. Noise Generator (Laplace(0, Delta f / eps) 또는 Gaussian(0, sigma^2) 난수 생성)
`-- Output Layer (노이즈 가산: y_tilde = y + Noise -> 사용자/분석가에게 안전한 통계값 반환)
```

선의 의미: 데이터베이스 질의 결과에 전역 민감도와 프라이버시 예산에 비례하는 수학적 노이즈를 주입하고 회계사를 통해 누적 손실을 추적하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **전역 민감도 산정기** | 함수 $f$에서 개별 레코드 1건의 **최대 영향력($\Delta f$)을 계산하여 노이즈 결정** | $L_1 / L_2$ Sens |
| **프라이버시 예산 ($\epsilon$)**| 시스템 허용 **프라이버시 손실 상한선 설정 ($\epsilon \in [0.1, 2.0]$)** | Epsilon / Delta |
| **노이즈 생성기** | 라플라스($L_1$) 또는 **가우시안($L_2$) 분포 기반 암호학적 난수 생성** | Noise Engine |
| **프라이버시 회계사** | RDP 기반 **누적 손실 정밀 계산 및 예산 초과 쿼리 한도 제어** | Moments Account |
| **기여도 클리핑기** | 개별 데이터 이상치가 **민감도를 폭증시키지 않도록 임계치 절단** | Clipping Bound |

#### 한줄 요약
- 민감도 산정기, 프라이버시 예산, 노이즈 생성기, 프라이버시 회계사, 기여도 클리핑기가 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DP-SGD (Differentially Private SGD)**: 딥러닝 학습 시 그래디언트를 클리핑하고 가우시안 노이즈를 주입하여 AI 모델이 특정 개인 데이터를 암기하는 것을 방지하는 알고리즘.

</details>

```text
DP 질의 수신, 민감도 산정, 예산 검증, 노이즈 가산 및 통계값 반환 파이프라인
        │
   1. [집계 질의 수신] 분석가가 질의를 제출하면 시스템이 질의의 전역 민감도($\Delta f$) 도출
        │
   2. [프라이버시 예산 검증] 프라이버시 회계사가 필요 예산($\epsilon_i$)과 누적 사용량 대조
        │
   ├─ [총 예산 초과 시] ➔ 질의 즉시 거부 및 접근 차단 (Privacy Budget Exhausted)
   ▼
3. [원시 통계 및 클리핑] 예산 충족 시 데이터베이스에서 쿼리 계산 및 개별 기여도 클리핑($C$) 적용
        │
   4. [라플라스 노이즈 가산] $\text{Laplace}\left(0, \frac{\Delta f}{\epsilon_i}\right)$ 난수를 추출하여 원시 통계값에 가산
        │
   ▼
5. [예산 차감 및 반환] 회계사 장부에서 예산을 차감하고 노이즈가 주입된 통계값($\tilde{y}$)을 분석가에게 반환
```

#### 한줄 요약
- 민감도 산정 → 프라이버시 예산 검증 → 클리핑 및 노이즈 생성 → 통계값 가산 반환 → 예산 차감 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **중앙형 DP** vs **로컬형 DP** vs **셔플형 DP**.

</details>

| 비교 항목 | 중앙형 차등 프라이버시 (Central DP) | 로컬형 차등 프라이버시 (Local DP) | 셔플형 차등 프라이버시 (Shuffle DP) |
|:---|:---|:---|:---|
| **노이즈 주입 주체** | **중앙 서버 (집계 후 노이즈 주입)** | **사용자 단말기 (전송 전 노이즈 주입)** | **중간 셔플러 노드 (익명화 믹싱)** |
| **중앙 서버 신뢰 요구**| **필수 (서버가 원본 평문 데이터를 보유)**| **불필요 (서버는 오직 노이즈 데이터만 수신)**| 최소 신뢰 (셔플러와 분석 서버 분리) |
| **통계 분석 정확도** | **매우 높음 (소량의 노이즈만으로 충분)**| **낮음 (개별 단말마다 노이즈 추가되어 누적)**| **중간~높음 (노이즈 증폭 효과 활용)** |
| **필요 데이터 표본 수** | 수천 ~ 수만 건 | **수백만 ~ 수천만 건 (대규모 단말 필요)**| 수십만 건 |
| **주요 상용 적용 사례**| **미국 인구조사국(US Census), 금융 통계** | **Apple iOS 텔레메트리, Google Chrome RAPPOR**| **연합학습 프라이버시 집계, IoT 센서망**|

#### 한줄 요약
- 중앙 DP는 고정확도 통계 분석용, 로컬 DP는 서버를 신뢰할 수 없는 대규모 단말용, 셔플 DP는 절충형 하이브리드이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Membership Inference Attack**: 머신러닝 모델의 출력 손실값(Loss)을 분석하여 특정 개인 데이터가 학습셋에 포함되었는지 추론하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 유사 질의를 수천 번 반복하여 노이즈를 평균화하고 **개인 원본을 역추론하는 공격** | **`RDP 기반 프라이버시 회계사 도입 및 총 예산(eps_total) 소진 시 차단`** | 반복 질의에 의한 노이즈 상쇄 방어 및 재식별 차단 |
| 극단적 이상치 레코드로 인한 **전역 민감도 폭증 및 데이터 품질 왜곡** | **개별 데이터 기여도 한도를 절단하는 `L2-Norm 클리핑(Clipping Bound)`** 적용 | 민감도 상한 고정 및 주입 노이즈 최소화 |
| AI 모델이 훈련 데이터를 과적합하여 **개인정보를 암기 후 출력하는 멤버십 추론** | **모델 학습 최적화에 `DP-SGD(Clipping + Gaussian Noise)` 필수 적용** | AI의 개인 데이터 암기 방지 및 멤버십 추론 방어 |
| 과도한 노이즈 주입으로 인한 비즈니스 의사결정 통계 왜곡 | **비즈니스 목적에 맞춘 `최적 엡실론(eps=0.5~2.0) 튜닝` 및 민감도 최적화** | 데이터 유용성과 프라이버시 보호의 최적 균형점 달성 |

#### 한줄 요약
- RDP 회계사로 질의를 제한하고, 클리핑으로 이상치 폭증을 막으며, DP-SGD로 AI 멤버십 추론을 방어한다.

## Ⅶ. 결론

- 빅데이터 분석 및 인공지능 학습 환경에서 데이터 활용성과 개인정보 보호 컴플라이언스(개인정보보호법 가명정보 결합)를 완벽히 양립시키는 **차등 프라이버시(Differential Privacy) 아키텍처는 전 세계 프라이버시 공학의 글로벌 표준**이며, 실무 구현 시 **중앙 DP와 로컬 DP의 서비스 특성별 최적 선택, 엄격한 프라이버시 회계사 기반 예산 관리, AI 모델 학습 시 DP-SGD 파이프라인 결합**을 통합 추진하여 신뢰성 높은 데이터 프라이버시 생태계 완성

#### 한줄 요약
- 차등 프라이버시는 수학적 ($\epsilon, \delta$)-DP 정의와 프라이버시 회계사 및 DP-SGD를 결합하여 완벽한 비식별화 통계를 실현하는 프라이버시 공학 표준이다.
