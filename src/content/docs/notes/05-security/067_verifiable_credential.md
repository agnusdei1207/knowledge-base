## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **VC (검증 가능 자격증명)**: 대학교나 경찰청이 포토샵으로 위조 불가능하게 블록체인 전자서명을 딱 찍어서 발급해 주는 '디지털 졸업장/진단서' 파일이다.
- **암호학적 증명**: "이거 내가 발급한 거 맞음" 하고 기관장(발급자)이 프라이빗 키로 도장(해시/서명)을 찍어놓은 암호화 데이터다.

</details>

- 정의: 발급 기관이 사용자의 자격 및 속성(Claim) 정보에 암호학적 전자서명을 부여한 위변조 불가능한 디지털 증명서 규격이다.
- 배경: 기존 종이 서류나 PDF 증명서는 포토샵으로 쉽게 위조가 가능하고, 이를 일일이 기관에 전화해 확인하는 대면 수동 검증 비용이 막대하기 때문이다.

#### 한줄 요약

- 종이 증명서 떼서 팩스로 보내던 짓 그만하고, 기관 도장(전자서명) 쾅 찍힌 파일(VC)을 스마트폰에 넣어 다녀라.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **VP (검증 가능 프레젠테이션)**: 보유자가 렌터카 회사에 면허증 낼 때, "이름, 주소 다 빼고 '성인/면허유효' 여부만 뽑아서 제출할게" 하고 쪼개서 다시 서명한 제출본이다.
- **선택적 공개 (Selective Disclosure)**: 내 폰에 저장된 전체 VC 데이터 중 검증 기관이 딱 요구하는 필수 속성만 쏙 빼서 보여주는 사생활 보호 기술이다.

</details>

- **3자 신뢰 아키텍처**: 발급자, 보유자, 검증자를 논리적/물리적으로 분리하여, 중앙 서버 호출 없이도 블록체인(DID 문서)을 통해 독립적 자격 수용을 가능케 한다.
- **원본 무결성 보장**: 암호학적 증명(디지털 서명)을 부착하여 포토샵 등 원본 위변조 시도를 원천 차단하고, 해시 검증을 통한 무결성을 100% 보장한다.
- **프라이버시 보호**: 선택적 공개(Selective Disclosure) 및 VP 구조를 통해 과도한 개인정보 제출을 막고 최소 수집 원칙(Privacy-by-Design)을 충족한다.

#### 한줄 요약

- 발급-보유-검증을 쪼개고, 위변조는 서명으로 원천 차단하고, 프라이버시는 VP(선택적 공개)로 지켜준다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **주장 (Claim)**: 증명서 안에 적혀있는 "이 사람은 서울대 나왔음", "이 사람은 99년생임" 같은 구체적인 내용(속성 키-값)이다.
- **상태 체계 (Status List)**: "어? 이 사람 저번 달에 음주운전으로 면허 취소됐네?" 하고 자격이 정지되거나 폐기된 상태를 알려주는 블록체인 전광판이다.

</details>

```text
[ VC 생태계 및 발급 구조 ]

[ 1. 발급자 (Issuer) ] ── ("주장(Claim) 확인하고 내 프라이빗 키로 서명함")
      │
      ▼
[ 2. VC (자격증명) ] ── ("암호학적 증명이 찍힌 완전무결한 증명서 생성 완료")
      │
      ▼
[ 3. 보유자 및 지갑 ] ── ("스마트폰 지갑에 VC 안전하게 저장하고 내 맘대로 관리함")
      │
      ▼
[ 4. VP (프레젠테이션) ] ── ("렌터카 회사가 나이만 요구하니까, VP로 나이만 쏙 빼서 제출함")
      │
      ▼
[ 5. 검증자 및 신뢰 상태 ] ── ("서명 무결성 확인 및 면허 취소 안 됐는지 블록체인에서 조회함")
```

| 구성요소 | 책임 | 비고 |
|:---|:---|:---|
| **발급자 (Issuer)** | 주체의 자격(Claim)을 체크하고 **비밀키로 암호화 서명한 VC를 발급함** | Issuer |
| **VC (자격증명)** | 사용자 정보, 발급/만료일, **암호학적 서명이 포함된 데이터 구조임** | Credential |
| **보유자 / 지갑** | 지갑(Wallet)에 VC를 암호화 보관하고 **자기 동의하에 VP를 생성해서 제출함** | Holder |
| **VP (프레젠테이션)** | 서비스 검증 목적에 맞게 **최소 주장 속성만 뽑아내서 조립한 제출용 팩트본임** | Presentation |
| **검증자 / 상태 체계** | 신뢰/상태 체계(블록체인)를 조회해서 **서명, 위조, 폐기 여부를 최종 판정함** | Verifier |

#### 한줄 요약

- 기관(발급자)이 서명한 증서(VC)를 폰(지갑)에 넣고, 필요한 것만 빼서(VP) 내면 상대(검증자)가 확인한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

```text
[ VC 발급 및 VP 제시 검증 흐름 ]

┌──────────────────────────────┐
│ 1. [원천 자료 대조 및 자격 주장(Claim) 철저한 검증]
│ ("발급자(경찰청)가 자체 DB 조회해서 홍길동이 면허 딴 거 확인함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [암호학적 증명 부착 및 서명 VC 생성]
│ ("경찰청 프라이빗 키로 쾅 도장(서명) 찍어서 폰 지갑으로 쏴줌")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [동의 기반 선택적 공개 및 VP 생성]
│ ("사용자가 렌터카 빌릴 때 나이/면허번호만 쏙 빼서 VP 조립 후 제출함")
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [서명 무결성 검증 및 발급자/상태(Status) 조회]
│ ("렌터카가 블록체인에서 서명 맞는지, 음주로 면허 정지(폐기) 안 됐는지 확인")
└──────────────┬───────────────┘
               ▼
    ┌──────────────────────────────┐
    │ 5. [목적 제한 원칙 준수 및 업무 적합성 판정]
    │ ("위조 없고 면허 유효기간 안 지났으니 렌트카 승인 완료!")
    └──────────────────────────────┘
```

### 동작 원리

1. 자격 심사: 발급자가 원천 DB 기반으로 사용자 신원 자격의 적격성을 대조.
2. VC 생성: 발급자 DID 비밀키로 속성과 증명 블록(Proof)을 서명 구성하여 VC 발급.
3. VP 구성: 보유자가 필수 속성만 선택하여 동의 서명이 포함된 프레젠테이션(VP) 도출.
4. 서명/상태 검증: 검증자가 DID 문서의 공개키로 무결성을 확인하고 VC 폐기 상태(Status List)를 철저한 검증.
5. 적합성 판정: 전자서명이 유효하더라도, 비즈니스 목적 및 인가 조건과 부합하는지 최종 판정.

#### 한줄 요약

- 발급자가 DB 체크 후 서명(VC) $\to$ 보유자가 속성 골라 제출(VP) $\to$ 검증자가 위조/폐기 여부 체크.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- (상단 설명 참조)

</details>

| 자격 증명 방식 | **종이 / PDF 증명서 (구형)** | **중앙 조회 증명 / API (과도기)** | **VC / W3C 표준 (미래)** |
|:---|:---|:---|:---|
| 핵심 특징 | **포토샵으로 대충 위조해서 주민센터 알바 눈속임하는 쓰레기** | **서류 낼 때마다 발급 기관 서버 찔러서 맞냐고 일일이 물어봄** | **서명 박힌 디지털 원본을 내가 쥐고, 검증자는 블록체인으로 체크함** |
| 핵심 특징 | 육안으로 도장/직인을 확인해야 해서 **대면 수동 서류 제출이 강제됨** | 검증자가 발급기관 중앙 서버로 **실시간 API를 쏴서 무결성을 확인함** | **VC** 기반 전자서명과 선택적 공개를 통해 **제3자가 독립적으로 철저한 검증함** |
| 한계 및 문제점 | 위변조가 너무 쉽고 자동화가 불가능해 **수작업 확인 비용이 막대함** | 발급 서버 죽으면 검증도 마비되고, **내가 어딜 가는지 발급 기관이 다 추적함** | 암호키/블록체인(DID) 프레임워크 기반 **인프라 구축 난이도가 빡셈** |

#### 한줄 요약

- 포토샵(PDF) 폐기하고, 중앙 서버 추적(API) 버리고, 블록체인 3자 독립 검증인 **VC 표준** 정답이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **W3C VC Data Model 2.0**: 국제 웹 표준화 기구에서 "전 세계 VC는 무조건 JSON-LD 포맷으로 만들어라" 하고 박아놓은 최신 규격이다.
- **W3C Bitstring Status List 1.0**: 수백만 명의 면허 정지(폐기) 목록을 `010101` 같은 비트열로 초고도 압축해서, 검증자가 블록체인에서 폐기 여부를 눈 깜짝할 새 초고속으로 조회하게 해주는 마법의 표준이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 모바일 면허증 만들었는데 **렌터카 앱에서 포맷 안 맞는다고 거부함** | 발급 기관마다 VC의 데이터 구문(JSON/XML)과 서명 알고리즘을 지들 맘대로 짬 | 국제 표준인 **W3C VC Data Model 2.0 전면 강제 채택** | 데이터 구문 및 서명 연동 등 글로벌 수준의 100% 상호운용성(Interoperability) 보장 |
| 제출할 때마다 폐기 조회하느라 **발급 기관 서버가 트래픽 터져서 뻗어버림** | 검증자가 실시간 상태(폐기)를 확인하려고 발급 기관 중앙 서버 API를 난사함 | 초고밀도로 압축된 상태 목록을 분산 저장하는 **W3C Bitstring Status List 1.0 규격 적용** | 발급 서버 부하(SPOF) 제거, 초고속 폐기 검증 및 프라이버시 중앙 추적(Tracking) 차단 |
| 검증자가 서명만 띡 믿었다가 **유령 대학에서 발급한 학위증을 프리패스 시켜줌** | 전자서명 무결성만 확인하고, '이 기관이 진짜로 자격을 발급할 권한이 있는가'를 안 따짐 | 신뢰 체계(Trust Registry) 매핑 및 비즈니스 **목적 적합성 심사 강제 적용** | 위조 서명 및 비인가 기관 발급 자격증의 무단 수용 원천 차단 |

#### 한줄 요약

- **W3C VC 2.0** 표준으로 구문 맞추고, **Bitstring Status List 1.0** 기반 폐기 초고속 철저한 검증해라.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **VC 수용 조건 (Acceptance Criteria)**: "서명 안 깨졌지? (무결성) + 발급 기관 믿을만해? (신뢰성) + 면허 정지 안 됐지? (미폐기 상태) + 기간 안 지났지? + 비즈니스 규칙 맞지?" $\to$ 이 5개를 모두 통과해야 최종 합격 도장을 찍어주는 철칙이다.

</details>

- 아날로그 종이 서류와 프라이버시 침해형 중앙 API 조회 방식의 한계를 극복하기 위해, **W3C VC 2.0 표준** 대상 입각한 암호학적 서명 증명(VC)을 발행하고, 검증자는 블록체인 기반으로 서명, 발급자 신뢰성, 미폐기 상태를 대조하는 엄격한 **VC 수용 조건** 기조를 확립함

#### 한줄 요약

- 종이 증명서 폐기하고, 서명+신뢰성+폐기+기한+목적 다 따지는 **VC 수용 조건** 준수해라.
