## 미리 알고가기

- **모바일 포렌식(Mobile Forensics)**: 모바일 기기·앱·백업·클라우드에서 디지털 증거를 수집·분석하는 절차
- **최초 잠금 해제 전(Before First Unlock, BFU)**: “비에프유”로 읽으며 기기를 켠 뒤 처음 잠금을 풀기 전이라 암호화 키 접근이 제한된 상태
- **최초 잠금 해제 후(After First Unlock, AFU)**: “에이에프유”로 읽으며 처음 잠금을 푼 뒤 일부 암호화 키가 메모리에 남아 더 많은 데이터에 접근 가능한 상태
- **응용 프로그래밍 인터페이스(Application Programming Interface, API)**: “에이피아이”로 읽으며 운영체제가 허용한 방식으로 앱 데이터에 접근하는 호출 경계
- **데이터베이스(Database, DB)**: “디비”로 읽으며 앱이 메시지·계정·설정 같은 구조화 데이터를 저장하는 공간
- **논리 추출**: 운영체제의 API나 백업 기능이 허용하는 데이터를 수집하는 방식
- **파일시스템 추출**: 디렉터리 구조와 앱 데이터베이스를 포함한 파일 체계를 수집하는 방식
- **물리 추출**: 저장장치의 비트열을 낮은 수준에서 복제하는 방식
- **타임스탬프**: 파일·메시지·접속 사건이 발생하거나 변경된 시각 기록

## Ⅰ. 개요

- 정의/개념: 모바일 기기·앱·백업·클라우드 증거의 적법한 획득·분석
- **배경/필요성**: 일반 저장매체 수집만으로 잠금 상태·앱·원격 데이터 확보 곤란

### 쉽게 이해하기 (학습용)

- 전원과 잠금 상태를 바꾸면 열 수 있는 자료도 달라지므로 처음 상태부터 기록한다.

## Ⅱ. 특징

- BFU·AFU에 따라 접근 가능한 키가 달라진다.
- 원격 변경 차단과 잠금·배터리 위험이 상충한다.
- 앱·백업·클라우드 흔적을 연결하고 도구별 결과를 검증한다.

### 쉽게 이해하기 (학습용)

- 같은 기기도 잠금이 처음 풀렸는지와 운영체제 상태에 따라 꺼낼 수 있는 자료가 달라진다.

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 현장 상태 | 화면·전원·잠금·통신·충전 및 주변 기록 |
| 격리·보존 | 원격 변경과 잠금 전환 위험을 비교해 상태 보존 |
| 추출·검증 | 가능 방식으로 획득하고 도구·해시·오류 기록 |
| 앱·시간 분석 | DB 관계·타임스탬프·시간대와 삭제 흔적 해석 |
| 연계 증거 | 권한 내 백업·클라우드·통신 기록 교차 확인 |

```text
  단말상태
     ↓
  보안경계
     ↓
  로컬증거
     ↓
  연계증거
     ↓
  획득기록
```

### 쉽게 이해하기 (학습용)

- 로컬 데이터와 클라우드 흔적을 별도 권한으로 확보하여 교차 확인

## Ⅳ. 원리 및 절차 흐름도

```text
권한상태기록
↓
보존전략판단
↓
추출선택시도
↓
검증분석
↓
연계보고
```

| 절차 | 설명 |
|:---|:---|
| 권한상태기록 | 수집 근거 및 전원·잠금·통신 상태 기록 |
| 보존전략판단 | 원격 명령·배터리 위험 고려해 격리 정함 |
| 추출선택시도 | 기기·잠금에 맞는 최소 변경 추출 시도 |
| 검증분석 | 해시·오류와 앱·시간 정보 분석 |
| 연계보고 | 클라우드 자료와 교차 검증 및 한계 보고 |

> 요약: 잠금·전원 상태 보존 후 최소 변경 추출 및 검증 수행

### 쉽게 이해하기 (학습용)

- 기기 조작은 증거를 변경하므로 이유와 결과를 모두 기록

## Ⅴ. 모바일 추출 방식 비교

| 비교축 | 논리 추출 | 파일시스템 추출 | 물리 추출 |
|:---|:---|:---|:---|
| 적용 기준 | 신속하고 변경이 적은 수집이 필요할 때 | 앱 관계·메타데이터를 분석할 때 | 비할당 영역까지 확보해야 할 때 |
| 핵심 특징 | API·백업 허용 데이터 수집 | 디렉터리와 앱 DB 구조 수집 | 저장 영역의 비트열 복제 |
| 한계 | 삭제·보호 데이터 누락 | 권한·암호화로 일부 파일 누락 | 암호화 키가 없으면 내용 판독 불가 |

### 쉽게 이해하기 (학습용)

- 저수준 추출을 수행해도 암호화 키 없으면 내용 판독 불가

## Ⅵ. 실무 사례

1. 켜진 단말의 **BFU·AFU와 원격 변경 위험 평가**

### 쉽게 이해하기 (학습용)

- 켜진 단말은 잠금 상태와 암호키 접근 가능성, 원격 삭제 위험을 함께 평가해 전원·통신 상태를 보존할 초기 조치를 결정한다.

## Ⅶ. 결론

- 모바일 기기의 상태 변경과 증거 소실을 막기 위해 조사 권한·BFU·AFU·통신 차단·클라우드 범위·추출 한계를 검토하여, 적법하고 재현 가능한 모바일 포렌식을 수행해야 한다.

### 쉽게 이해하기 (학습용)

- 초기 상태를 함부로 바꾸지 않아야 접근 가능한 증거와 조사 신뢰성을 함께 보존할 수 있음
