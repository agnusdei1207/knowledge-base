## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **모바일 포렌식(Mobile Forensics / NIST SP 800-101 Rev.1 & ISO/IEC 27037)**: 스마트폰, 태블릿 등 모바일 기기의 플래시 메모리, 통신 칩셋(SIM), 내부 데이터베이스(SQLite), 클라우드 동기화 백업으로부터 통화 내역, 메시지, 메신저 대화(카카오톡/텔레그램), 위치 정보, 미디어 아티팩트를 법적 절차에 따라 추출·분석·복원하는 포렌식 분야.
- **하드웨어 암호화 및 원격 초기화 결함(Hardware Encryption & Remote Wipe Defect)**: 모바일 단말은 Secure Enclave/TrustZone 기반의 하드웨어 전용 암호화가 적용되어 있어, 단말 전원이 꺼질 경우 암호화 키가 RAM에서 소멸(BFU 상태 진입)하여 복호화가 불가능해지거나, 네트워크가 연결된 상태에서 피의자가 원격 초기화(Remote Wipe) 명령을 전송하여 증거가 영구 소실되는 구조적 취약점.

</details>

- 정의/개념: 모바일 증거를 안전하게 확보하기 위해 **현장 전원 및 통신 격리(패러데이 백/비행기 모드) $\rightarrow$ 잠금 상태 식별(BFU vs AFU) $\rightarrow$ 3대 추출 기법(논리/파일시스템/물리) 적용 $\rightarrow$ SQLite DB 카빙 및 타임라인 분석 $\rightarrow$ 클라우드 백업 교차 검증** 을 집행하는 **모바일 디지털 증거 획득 아키텍처**
- 배경/필요성: 모바일 OS(iOS/Android)의 샌드박스 보안 및 풀 디스크 암호화(FDE/FBE) 고도화에 대응하여, 증거 훼손 없이 법정 증거능력을 확보할 수 있는 표준 수사 절차 확립 요구

#### 한줄 요약
- 전파 차단과 전원 유지를 통해 BFU/AFU 상태를 판별하고, 논리·파일시스템·물리 추출로 모바일 증거를 획득한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **모바일 단말의 2대 암호화 상태**:
  - **BFU (Before First Unlock)**: 단말 재부팅 후 사용자가 최초 비밀번호를 입력하기 전 상태. 마스터 암호화 키가 메모리에 로드되지 않아 거의 모든 사용자 데이터가 하드웨어 암호화로 잠겨 있음 (추출 극도로 제한).
  - **AFU (After First Unlock)**: 재부팅 후 최소 1회 이상 비밀번호를 입력한 후 화면이 잠긴 상태. 복호화 키가 RAM에 잔존하여 포렌식 도구를 통해 앱 데이터 및 DB 획득 가능 (수사의 핵심 타겟).

</details>

- **통신 격리(Network Isolation)의 절대성**: 압수 즉시 패러데이 백(Faraday Bag) 투입, 비행기 탑승 모드 전환, SIM 카드 분리를 통해 원격 공장초기화(Remote Wipe) 신호 원천 차단
- **전원 유지(Power Preservation) 강제**: AFU 상태의 암호화 키 소멸을 방지하기 위해 외장 배터리를 상시 연결하여 전원 공급 유지
- **3대 추출 레벨의 단계적 적용**: 기기 모델, OS 버전, 보안 패치 수준에 따라 논리적(Logical), 파일시스템(File System), 물리적(Physical) 추출 방식을 최적 선별

#### 한줄 요약
- BFU/AFU 암호화 상태 판별, 패러데이 백 통신 격리, 상시 전원 유지, 3단계 추출 기법을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **모바일 포렌식 4대 핵심 컴포넌트**:
  1. **Isolation Equipment**: 패러데이 백, RF 차폐 챔버, SIM 클론 카드.
  2. **Extraction Framework**: Cellebrite UFED, Oxygen Forensic, MSAB XRY 등 상용 덤프 도구.
  3. **Decryption & Brute-force Engine**: 하드웨어 가속기 기반 패스코드 무차별 대입 및 취약점 익스플로잇.
  4. **App DB Parser & Carving**: SQLite 데이터베이스 WAL(Write-Ahead Log) 복원 및 삭제 레코드 파싱기.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 현장 확보 및 통신 격리 계층 (First Response & Network Isolation) ] │
│  ├─ 압수 즉시 패러데이 백(Faraday Bag) 봉인 ➔ [ 원격 공장초기화 100% 차단]│
│  └─ [ 보조배터리 즉시 연결 ➔ 전원 차단 방지 (AFU 암호화 키 잔존 유지) ] │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (잠금 상태 판별)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 단말 잠금 해제 및 추출 계층 (Unlock & Multi-level Extraction) ]    │
├───────────────────┬───────────────────┬─────────────────────────────────┤
│ [ 1. 논리적 추출 ]│ [ 2. 파일시스템 ] │ [ 3. 물리적 추출 (Physical) ]   │
│ ├─ 백업 API 호출  │ ├─ 루트 파일 구조 │ ├─ eMMC/UFS 칩 비트스트림 덤프  │
│ └─ 연락처/사진/SMS│ └─ [ App SQLite ] │ └─ [ 비할당 영역 삭제 복원 ]    │
└───────────────────┴───────────────────┴─────────────────────────────────┘
                                     │ (데이터 획득 및 해시 검증)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 아티팩트 파싱 및 랩 분석 계층 (Database Parsing & Carving) ]        │
│  ├─ SQLite WAL/Freelist 카빙 ➔ 메신저(카카오톡/텔레그램) 삭제 메시지 복원│
│  └─ [ 타임라인 분석: 통화 기록, GPS 위치 로그, 사진 EXIF 메타데이터 분석]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (클라우드 증거 교차 검증)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 클라우드 연계 교차 검증 계층 (Cloud Forensics Cross-Validation) ]  │
│  └─ [ 영장 기반 Google Drive/iCloud 백업 데이터 획득 ➔ 단말 증거 대조 ]  │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 현장에서 통신 격리와 전원을 유지한 후, 3단계 추출을 수행하고 SQLite DB를 분석하여 클라우드 백업과 교차 검증하는 구조

| 구성요소 | 핵심 역할 및 기능 | 주요 기술 및 도구 | 비고 |
|:---|:---|:---|:---|
| **통신 격리 장비** | 외부 무선 신호(Cellular, Wi-Fi, BT)를 차단하여 원격 삭제 방어 | Faraday Bag, RF Shield Box | Isolation |
| **논리적 추출기 (Logical)** | OS 백업 프로토콜 및 ADB/iTunes 백업 API를 활용한 데이터 수집 | ADB Backup, iTunes Backup API | Fast / Safe |
| **파일시스템 추출기** | OS 파일시스템 전체 구조 및 서드파티 앱 샌드박스 내부 접근 | Checkm8, Android Rooting 취약점 | App DB Access |
| **물리적 추출기 (Physical)**| 낸드 플래시 메모리의 0과 1 비트열 전체를 1:1 비트스트림 덤프 | Chip-off, JTAG, ISP, Bootloader Exploit | Deep Carving |
| **SQLite 파서** | DB 비할당 슬랙 공간 및 WAL 파일에서 삭제된 레코드 복원 | SQLite DB Browser, Undark, Forensic Parser | Deleted Data |

#### 한줄 요약
- 통신 격리 장비, 3대 추출기(논리/파일시스템/물리), SQLite 파서, 클라우드 연계 검증으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **모바일 포렌식 5단계 수사 시퀀스**:
  1. 현장 통신 격리 및 전원 보존 상태 식별
  2. 단말 잠금 상태(BFU/AFU) 확인 및 우회
  3. 최적 추출 기법(논리/파일시스템/물리) 적용 및 해시 생성
  4. 앱 데이터베이스 파싱 및 삭제 아티팩트 복원
  5. 클라우드 백업 데이터 교차 검증 및 보고서 작성

</details>

```text
1. [현장 통신 격리 및 전원 유지]
    ├─ 현장에서 폰 발견 즉시 비행기 모드 전환 및 패러데이 백 투입
    └─ [화면 켜짐 상태 확인 ➔ 보조배터리 연결하여 AFU 상태 강제 유지]
            │
            ▼
2. [단말 상태 판별 및 잠금 우회]
    ├─ BFU 상태(재부팅 직후) ➔ 취약점 기반 부트로더 우회 또는 패스코드 해제 시도
    └─ AFU 상태(잠금 화면) ➔ 포렌식 전용 하드웨어 도구(Cellebrite) 연결
            │
            ▼
3. [다단계 데이터 추출 및 무결성 확보]
    ├─ 1차 논리 백업 ➔ 2차 파일시스템 전체 덤프 ➔ 가능 시 물리 덤프(Raw Image)
    └─ [획득 완료 즉시 SHA-256 해시값 산출 및 연계보관부(CoC) 기명 날인]
            │
            ▼
4. [SQLite DB 파싱 및 삭제 메시지 복원]
    ├─ 카카오톡 `kakaotalk.db` 및 텔레그램 DB 추출
    └─ [SQLite Write-Ahead Log(WAL) 파일 카빙을 통해 삭제된 대화 복원]
            │
            ▼
5. [클라우드 백업 교차 검증 및 증거화]
    ├─ 영장 기반 통신사 기지국 위치 로그 및 구글 계정 동기화 데이터 확보
    └─ [단말 내 사진 GPS 메타데이터와 클라우드 위치 로그 1:1 대조 ➔ 최종 보고서 작성]
```

**동작 원리**

1. **원격 삭제 원천 방어**: 전파 차단 가방을 통해 증거 인멸 시도를 현장 진입 1초 내에 차단
2. **암호화 키 보존**: 화면이 켜져 있거나 AFU 상태인 단말의 전원을 유지하여 복호화 가능성 극대화
3. **손상 없는 점진적 추출**: 위험도가 낮은 논리 추출부터 시작하여 고위험 물리 추출로 순차 접근
4. **저장소 미세 흔적 복원**: SQLite DB의 삭제 마킹된 레코드 및 프리리스트(Freelist)를 정밀 분석하여 복구
5. **다각적 알리바이 검증**: 단말 로컬 데이터와 클라우드 서버 로그를 교차 대조하여 조작 가능성 완전 배제

#### 한줄 요약
- 통신 격리/전원 유지, BFU/AFU 판별, 다단계 추출, SQLite WAL 복원, 클라우드 교차 검증 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **모바일 3대 추출 기법 비교**:
  - 논리적 추출 (Logical): API를 통한 표준 데이터 수집 (빠르고 안전, 삭제 데이터 제외).
  - 파일시스템 추출 (File System): 앱 샌드박스 내부 접근 (DB 및 설정 파일 포함).
  - 물리적 추출 (Physical): 플래시 메모리 비트스트림 덤프 (삭제 파일 복원 가능, 암호화 시 제약).

</details>

| 비교 항목 | 논리적 추출 (Logical) | 파일시스템 추출 (File System) | 물리적 추출 (Physical) |
|:---|:---|:---|:---|
| **추출 범위** | **연락처, SMS, 사진, 통화 기록** | **앱 DB, 시스템 로그, 캐시, 설정** | **비할당 영역 포함 전체 낸드 비트열**|
| **삭제 데이터 복원**| **불가 (정상 파일만 수집)** | **제한적 복원 (DB 잔여 레코드)** | **최대 복원 가능 (비할당 공간 카빙)**|
| **단말 위험도** | **매우 낮음 (공식 API 활용)** | 낮음 (권한 상승 필요) | 중간~높음 (칩셋 분리 시 파손 위험) |
| **소요 시간** | 수 분 ~ 수십 분 | 1 ~ 2시간 | 수 시간 이상 |
| **주요 한계점** | 메신저 DB 상세 내역 수집 불가 | 하드웨어 전용 암호화 해제 필수 | **FBE 파일 암호화 시 평문 판독 불가** |

#### 한줄 요약
- 논리적 추출은 표준 API 수집, 파일시스템 추출은 앱 DB 분석, 물리적 추출은 비할당 영역 전체 복원이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-101 Rev.1 및 CFTT (Computer Forensics Tool Testing)**: 모바일 포렌식 수사 가이드라인 및 포렌식 도구의 증거 훼손 여부를 사전 검증하는 NIST 테스트 프로그램.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 모바일 단말 압수 현장에서 통신을 차단하지 않아 **피의자 공범이 원격 공장초기화(Remote Wipe)를 실행하여 모든 증거 영구 멸실** | **현장 즉시 패러데이 백(Faraday Bag) 투입, 비행기 탑승 모드 전환 및 SIM 카드 물리적 분리 조치 강제** | 원격 데이터 삭제 시도 100% 원천 차단 및 증거 보존 |
| 단말 배터리 방전으로 전원이 꺼지면서 **단말이 BFU(Before First Unlock) 상태로 진입하여 암호화 키 소멸로 데이터 추출 실패** | **현장 진입 즉시 대용량 보조배터리를 단말에 연결하여 전원 ON 및 AFU(After First Unlock) 상태 지속 유지** | 메모리 내 복호화 키 보존 및 메신저 DB 추출 성공률 극대화 |
| 검증되지 않은 오픈소스 툴을 사용하여 데이터를 추출하다가 **데이터 오염이 발생하여 법정에서 증거능력 결함으로 무죄 선고** | **NIST CFTT(도구 시험)를 통과한 공인 상용 포렌식 도구(Cellebrite 등)를 사용하고 도구 검증 보고서를 첨부** | 증거 추출 과정의 과학적 무결성 100% 입증 및 법정 증거 채택 |

#### 한줄 요약
- 패러데이 백으로 원격 삭제를 막고, 보조배터리로 AFU 키를 보존하며, CFTT 검증 도구로 무결성을 입증한다.

## Ⅶ. 결론

- 스마트폰 중심 디지털 범죄 수사의 성패를 가르는 **모바일 포렌식 아키텍처**는 디지털 증거 과학의 최전선 영역이며, 실무 구현 시 **NIST SP 800-101 Rev.1 국제 수사 지침 준수**, **현장 압수 즉시 패러데이 백 통신 격리 및 상시 전원 유지**, **BFU/AFU 상태 판별에 따른 정밀 추출 기법(논리/파일시스템/물리) 적용**, **SQLite DB 카빙 및 클라우드 백업과의 다각적 교차 검증**을 통합 구축하여 최고 수준의 과학적 무결성과 법적 증거능력을 완성

#### 한줄 요약
- 패러데이 격리와 전원 유지 및 다단계 추출과 SQLite WAL 복원을 통해 완벽한 모바일 포렌식을 완성한다.
