## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **제로 트러스트 네트워크 접근(Zero Trust Network Access, ZTNA)**: 검증된 주체와 단말에 승인된 특정 애플리케이션에 대한 동적 1:1 세션 통로만 제공하는 보안 접근 기술이다.
- **가상 사설망(Virtual Private Network, VPN)**: 암호화 터널을 통해 원격 단말을 사내 L3/L4 네트워크 전체에 연결하는 고정형 경계접속 기술이다.
- **측면 이동(Lateral Movement)**: 단말 침해 성공 후 네트워크 내부의 타 자원으로 권한 및 공격을 확산하는 행위이다.

</details>

- 정의/개념: 검증된 주체에 앱 단위 통로만 제공하는 **ZTNA**
- 배경/필요성: VPN의 망 단위 접속은 **측면 이동•앱 노출** 유발

#### 한줄 요약

- 원격 단말을 사내 망 전체에 접속시키지 않고 검증된 주체에게 승인된 특정 앱 통로만 1:1 동적 구성한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **앱 단위 접근(App-level Access Control)**: 네트워크 L3 접속을 차단하고 L7 애플리케이션 레벨에서 세션 단위로 접근 권한을 세분화하여 제어하는 방식이다.
- **기원 서버 비공개(Origin Server Cloaking / Dark IP)**: 아웃바인드 전용 앱 커넥터를 통해 실제 애플리케이션 IP 및 방화벽 포트를 외부 인터넷에 절대 노출하지 않는 구조이다.

</details>

- **앱 단위 접근** 통제 정책으로 사용자 신원 및 기기 상태에 부합하는 승인 앱만 선별 연결한다.
- **기원 서버 비공개** 구조를 적용해 외부 스캐닝 공격과 직접 접속 시도를 근본 차단한다.
- 미승인 내부 자원•IP 대역 은폐로 공격 표면 최소화

#### 한줄 요약

- 인프라 주소 노출 없이 L7 프록시 기반으로 허가된 앱 세션만을 동적 세그먼테이션하여 연결한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정책 브로커(Policy Broker)**: 신원, 기기 무결성, 맥락 신호를 검증하여 앱 접속 승인 여부를 종합 평가하고 정책을 전달하는 컨트롤 플레인이다.
- **앱 커넥터(App Connector)**: 내부 망에서 클라우드/브로커 방향으로 인바운드가 아닌 아웃바운드 세션을 맺어 승인된 비공개 앱 연결을 중계하는 데이터 플레인이다.

</details>

```text
[ZTNA]
   |
   +-- [사용자·기기]
   +-- [정책 브로커·신호]
   +-- [앱 커넥터]
   +-- [비공개 앱]
   `-- [로그·가용성]
```

선의 의미: 접근 주체 검증, 정책 브로커 평가, 앱 커넥터 중계, 비공개 앱 접속 및 운영 감사를 아우르는 ZTNA 아키텍처이다.

| 구성요소 | 책임 |
|:---|:---|
| 사용자·기기 | 사용자 신원 자격 증명 및 단말 상태(Posture) 신호 전달 |
| 정책 브로커·신호 | **정책 브로커**의 신원•기기 상태•위험 평가 및 세션 승인 수립 |
| 앱 커넥터 | **앱 커넥터**의 아웃바운드 터널링 기반 승인 앱 1:1 안전 중계 |
| 비공개 앱 | 외부 포트 오픈 없이 숨겨진 보호 대상 애플리케이션 자산 |
| 로그·가용성 | 세션 트래픽 실시간 모니터링, 로그 보존 및 이중화 가용성 보장 |

#### 한줄 요약

- 정책 브로커가 신원과 단말 무결성을 평가하면 아웃바운드 앱 커넥터가 은폐된 내부 앱으로 1:1 안전 터널을 중계한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **제한 세션(Scoped Session)**: 지정된 앱과 특정 작업 행위, 제한 시간 내에서만 유지되는 격리된 암호화 세션이다.
- **연결 로그(Connection Log)**: 주체, 단말, 연결 앱, 세션 시간, 트래픽 양을 정밀 수집한 감사 증적이다.
- **위험 신호 환류(Risk Signal Feedback)**: 세션 동작 중 발생한 이상 신호를 정책 브로커로 즉시 피드백하여 차단·재인증을 유도하는 메커니즘이다.
- **신원•기기•위험 정책 판정(Identity/Device/Risk Policy Evaluation)**: 요청자의 신원, 단말 백신/OS 무결성, 접속 위험 점수를 대조하는 단계이다.
- **제한 세션 정책 생성(Scoped Session Policy Generation)**: 허용할 목적지 앱과 세션 만료 조건을 동적 정의하는 단계이다.
- **발신 커넥터•앱 터널 설정(Outbound Connector & App Tunnel Setup)**: 인바운드 포트 수신 없이 커넥터가 아웃바운드로 연결 통로를 생성하는 단계이다.
- **세션 행위•연결 로그 수집(Session Activity & Connection Log Collection)**: 세션 중 수행되는 동작 및 트래픽 증적을 수집하는 단계이다.
- **세션 위험 재평가(Session Risk Re-evaluation)**: 단말 위험 신호 변경 시 세션 유지 여부를 즉시 재계산하는 단계이다.

</details>

```text
[사용자·기기]
      |
      `-- 대상 앱 접근 요청
                |
                v
[정책 브로커]
      |
      v
1. 신원·기기·위험 정책 판정
      |
      v
2. 제한 세션 정책 생성
      |
      v
[앱 커넥터]
      |
      v
3. 발신 커넥터·앱 터널 설정
      |
      v
[비공개 앱] -- 앱 응답
      |
      v
+----------------------------------+
| 세션 유지 중                     |
|                                  |
|  4. 세션 행위·연결 로그 수집     |
|             |                    |
|             v                    |
|       [정책 브로커]              |
|             |                    |
|             v                    |
|  5. 세션 위험 재평가             |
|             |                    |
|             `-- 유지·제한·종료   |
+----------------------------------+
      |
      `-- 접근 결과 ----> [사용자·기기]
```

### 동작 원리

1. **신원•기기•위험 정책 판정**: 단말 무결성•신원 검증
2. **제한 세션 정책 생성**: 앱•권한•만료 조건 정의
3. **발신 커넥터•앱 터널 설정**: 아웃바운드 앱 세션 형성
4. **세션 행위•연결 로그 수집**: 트래픽•동작 증적 수집
5. **세션 위험 재평가**: 위협 시 차단•재인증

#### 한줄 요약

- 접근 요청 검증, 아웃바운드 전용 터널 형성, 세션 로그 수집 및 위협 감지 시 실시간 차단으로 연결 완결성을 보장한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **앱 프록시(App Proxy)**: 특정 웹 프로토콜(HTTP/HTTPS) 요청을 수신하여 내부 서버로 전달하는 웹 게이트웨이 기술이다.

</details>

| 원격 접근 방식 | ZTNA | 전통 VPN | 애플리케이션 프록시 |
|:---|:---|:---|:---|
| 적용 기준 | 앱 단위 동적 최소 권한 접속 | 사내 전체 L3/L4 풀 네트워크 접속 | 웹 기반 특정 서비스 외부 공개 |
| 핵심 특징 | **ZTNA** 기반 Dark IP 및 L7 앱 중계 | **VPN** 중심 IP 대역 풀 터널링 | **앱 프록시** 기반 웹 트래픽 단순 역방향 중계 |
| 한계 | 브로커/커넥터 고가용성 설계 필요 | 계정 탈취 시 내부 전체 침해(**측면 이동**) | 웹 외 프로토콜 제어 불가 및 직접 주소 노출 |

#### 한줄 요약

- 전통 VPN의 사내 네트워크 전면 오픈 방식과 달리 ZTNA는 신원 및 단말 검증 기반 1:1 앱 동적 터널만을 형성한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST SP 800-207**: 제로 트러스트 컴포넌트 간 신호 전달 및 정책 집행 기준 규격 지침이다.
- **CISA ZTMM 2.0 (Zero Trust Maturity Model 2.0)**: ZTNA의 단계적 성숙도 측정 및 도메인별 이행 표준 모델이다.
- **다중 커넥터(Multi-Connector High Availability)**: 커넥터 노드 다중화를 통한 무중단 앱 중계 보장 기법이다.
- **직접 경로 차단(Direct Path Blocking / Bypass Prevention)**: ZTNA를 우회하는 모든 사내 방화벽 직통 통신을 원천 차단하는 세그먼테이션 기법이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 표준 아키텍처 및 역할 부재 | **NIST SP 800-207** 기준 준용 | 브로커-커넥터 간 역할 명확화 및 상호운용성 확보 |
| VPN replacement 이행 우려 | **CISA ZTMM 2.0** 이행 프레임워크 적용 | 중요 비공개 앱 단위 단계별 ZTNA 전환 |
| 단일 장애점(PoF) 및 직접 우회 | **다중 커넥터** 배치 및 **직접 경로 차단** | 서비스 무중단 연속성 보장 및 우회 접속 근본 차단 |

#### 한줄 요약

- 브로커 및 커넥터 다중화로 가용성을 확보하고, 방화벽 직접 통신을 차단하여 ZTNA 우회 경로를 제거한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **원격 접근 방식 선택 기준(Remote Access Selection Criteria)**: 보안 민감도, 애플리케이션 프로토콜, 단말 상태에 맞춰 ZTNA, VPN, 앱 프록시를 최적 배치하는 평가 기준이다.

</details>

- **원격 접근 방식 선택 기준**에 의거하여 핵심 비공개 자산은 **ZTNA**, 레거시 전체 망은 **VPN**, 일반 웹은 **앱 프록시**를 적용한다.

#### 한줄 요약

- 비공개 앱은 **ZTNA**, 레거시 전체 망은 **VPN** 적용
