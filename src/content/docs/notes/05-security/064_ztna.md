## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **ZTNA(Zero Trust Network Access, 제로 트러스트 네트워크 접근 / Gartner)**: 사용자가 사내 네트워크(L3/L4) 전체에 진입하는 것을 전면 차단하고, 신원(Identity)과 단말 보안 상태(Posture)가 명시적으로 검증된 주체에 한하여 사전에 승인된 특정 개별 애플리케이션(L7)에 대해서만 1:1 암호화 터널을 동적으로 형성하는 제로 트러스트 원격 접속 기술.
- **전통 VPN의 망 단위 개방 취약성(Broad Network Access Defect)**: 레거시 IPsec/SSL VPN은 터널 수립 시 원격 사용자에게 사내 서브넷 전체 IP 대역에 대한 브로드밴드 접근을 허용하므로, 원격 단말 1대가 악성코드에 감염되었을 때 사내 모든 자원으로 횡적 이동(Lateral Movement)되는 구조적 취약성을 내포.

</details>

- 정의/개념: 인프라 IP/포트를 외부에 노출하지 않는 **다크 IP(Dark IP)** 및 **아웃바운드 전용 커넥터(App Connector)** 를 기반으로, **신원/단말 상태 검증 $\rightarrow$ 정책 브로커(Policy Broker) 세션 승인 $\rightarrow$ 1:1 앱 마이크로 터널 형성 $\rightarrow$ 런타임 위험 지속 평가** 를 집행하는 **애플리케이션 격리 접근 아키텍처**
- 배경/필요성: VPN은 터널 1개를 여는 대가로 사내 서브넷 전체를 함께 열어 감염 단말 1대가 곧 내부망 전역 접근 권한이 되고 게이트웨이 IP·포트도 상시 노출되므로, 인바운드를 모두 닫고 사내 커넥터가 밖으로 뚫은 아웃바운드 터널과 사용자 터널을 승인 이후에만 결속해 주는 브로커 계층을 인터넷 엣지에 둘 요구

#### 한줄 요약
- ZTNA의 이득은 암호화 강도가 아니라 접근 허용 단위를 서브넷에서 애플리케이션으로 좁혀 침해 시 도달 가능한 범위를 미리 줄여 둔 데서 나온다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **다크 IP(Dark IP / 인프라 완전 은닉)**: 사내 보호 자원(ERP, DB 등)이 외부 인터넷으로부터의 인바운드 연결 포트(Inbound Port 80, 443, 22 등)를 일절 개방하지 않고, 오직 내부 커넥터가 브로커를 향해 아웃바운드(Outbound 443) 통신만 유지하여 공격자의 포트 스캐닝(Shodan 등)에 완전히 보이지 않도록 은닉하는 기술.
- **L7 애플리케이션 단위 세분화(App-Level Micro-Tunneling)**: 네트워크 서브넷 단위가 아닌 개별 URL, FQDN, 서비스 포트 단위로 세션을 격리하여 허가받지 않은 타 시스템으로의 횡적 이동을 원천 봉쇄.

</details>

- **인바운드 포트 전면 폐쇄 (Zero Inbound Open Ports)**: 사내망 방화벽의 인바운드 룰을 완전 차단하여 DDoS 및 제로데이 익스플로잇 사전 방어
- **제어 평면과 데이터 평면의 물리적 분리**: 정책 브로커(Control Plane)가 인가를 완료하기 전까지 사용자는 데이터 평면(Data Plane)에 접근 불가
- **단말 보안 상태 지속 평가 (Continuous Posture Assessment)**: 세션 중 단말 백신/EDR 비활성화 감지 시 터널 즉시 단절

#### 한줄 요약
- 인바운드 포트를 모두 닫아 정찰 자체를 무력화한 대가로 모든 트래픽이 외부 브로커와 게이트웨이를 경유해야 하며, 그만큼 경로 지연과 서비스 사업자 의존이 늘어난다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **ZTNA 3대 핵심 아키텍처 구성요소**:
  1. **ZTNA Client (엔드포인트 에이전트)**: 사용자 단말에 상주하여 신원 토큰 및 기기 상태(OS 패치, 백신, 디스크 암호화)를 수집하는 모듈.
  2. **Policy Broker (정책 브로커 / 제어 평면)**: IdP 및 EDR과 연동하여 신뢰 점수를 평가하고 세션 수립을 승인하는 컨트롤 타워.
  3. **App Connector (앱 커넥터 / 데이터 평면)**: 사내망 내부에 위치하여 외부 브로커와 아웃바운드 TLS 터널을 유지하고 트래픽을 중계하는 프록시.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 제어 평면 (Control Plane: 정책 평가 및 브로커링) ]                    │
│                                                                         │
│  [ 사용자 / 엔드포인트 기기 ] ────(인증/기기상태 전송)───▶ [ 정책 브로커 (Policy Broker) ]
│  (ZTNA Client Agent)                                  │ (신뢰 평가 및 접근 승인)
└───────────────────────────────────────────────────────┼─────────────────┘
                                                        │ (1:1 세션 바인딩 지시)
┌───────────────────────────────────────────────────────▼─────────────────┐
│ [ 데이터 평면 (Data Plane: 아웃바운드 기반 1:1 앱 중계) ]               │
│                                                                         │
│  [ 사용자 기기 ] ──(mTLS 터널)──▶ [ ZTNA Gateway ] ◀──(아웃바운드 TLS)── [ 사내 앱 커넥터 ] ──▶ [ 비공개 사내 앱 ]
│                                  (클라우드 엣지)   (인바운드 포트 0개)   (App Connector)     (Dark IP)
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 사용자가 브로커로부터 인증/기기 검증을 받아 승인을 획득하면, 사내망 커넥터가 개설한 아웃바운드 터널과 게이트웨이에서 1:1로 결속되는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **ZTNA Client** | 엔드포인트 단말의 사용자 신원 증명 및 EDR 무결성 텔레메트리를 브로커로 전송 | Endpoint Agent |
| **정책 브로커 (Policy Broker)**| IdP/EDR과 연동하여 접근 정책(ABAC)을 평가하고 1:1 세션 수립 승인/거부 판정 | Control Plane |
| **앱 커넥터 (App Connector)** | 사내망 내부에서 게이트웨이로 아웃바운드 전용 TLS 터널을 뚫어 트래픽 중계 | Dark IP Connector|
| **비공개 사내 애플리케이션** | 인터넷에 공인 IP나 포트를 일절 노출하지 않고 커넥터 뒤에 안전하게 은닉된 자원 | Protected App |
| **ZTNA 게이트웨이 (Edge)** | 사용자의 인바운드 터널과 커넥터의 아웃바운드 터널을 브로커 승인 하에 안전하게 결속 | Traffic Stitching|

#### 한줄 요약
- 커넥터가 아웃바운드로만 연결되므로 사내망에는 외부에 열어 줄 포트가 남지 않지만, 그 대신 커넥터가 끊기면 해당 앱은 외부에서 존재조차 확인되지 않는 상태가 된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ZTNA 1:1 세션 수립 5단계 시퀀스**:
  1. 클라이언트가 브로커로 접속 요청 및 단말 텔레메트리 전송
  2. 브로커가 신원/기기 검증 후 특정 앱 인가 토큰 발급
  3. 사내 커넥터가 게이트웨이로 아웃바운드 터널 개설
  4. 게이트웨이에서 두 터널을 스티칭(Stitching)하여 1:1 L7 통신 개시
  5. 런타임 위험 재평가 및 조건 불일치 시 세션 즉시 단절

</details>

```text
1. [인증 및 단말 상태 검증] 사용자가 ZTNA 클라이언트를 통해 IdP 로그인(MFA) 및 EDR 무결성 데이터 브로커로 전송
            │
            ▼
2. [세션 정책 및 앱 인가 판정]
    ├─ 브로커가 정책 평가: "인사팀 소속 + 단말 OS 최신 패치 완료" 확인
    └─ [특정 사내 인사 시스템(L7 URL)에 대해서만 1시간 유효 세션 인가]
            │
            ▼
3. [아웃바운드 터널 결속 (Stitching)]
    ├─ 사내망 커넥터가 외부 게이트웨이로 아웃바운드 연결(TCP 443) 유지
    └─ 게이트웨이가 사용자 mTLS 터널과 커넥터 터널을 1:1로 상호 결속
            │
            ▼
4. [L7 앱 전용 통신 집행] 사용자는 오직 해당 인사 시스템과만 통신 (사내망 타 서버 IP 접근 불가)
            │
            ▼
5. [세션 중 위험 감시 및 즉시 차단] 작업 중 단말기에서 랜섬웨어 행위 감지 ➔ [브로커가 즉각 터널을 강제 파기]
```

**동작 원리**

1. **포트 스캐닝 원천 차단**: 외부 방화벽에 오픈 포트가 존재하지 않아 공격자의 정찰(Reconnaissance) 무력화
2. **최소 네트워크 노출**: 클라이언트는 사내망 라우팅 테이블(IP 대역)을 획득하지 못하고 오직 목적지 앱만 인지
3. **선검증 후연결 (Verify then Connect)**: 패킷이 사내 인프라에 도달하기 전에 클라우드 브로커에서 보안 검증 완결
4. **횡적 감염 차단**: 감염된 재택 단말이 침투하더라도 인접 DB나 서버로의 L3 브로드캐스트/스캔 불가
5. **동적 세션 생애주기 관리**: 위험 신호 발생 시 밀리초 단위로 특정 앱 터널만 선별적으로 차단

#### 한줄 요약
- 두 터널을 게이트웨이에서 결속하는 방식이라 사용자에게는 목적지 앱 외의 사내 IP 대역이 애초에 전달되지 않으며, 이 점이 VPN과 갈리는 실제 비용 차이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **원격 접속 3대 기술 비교**: 전통 VPN(L3/L4 망 개방), ZTNA(L7 앱 격리), 리버스 프록시(L7 웹 전용)의 비교.

</details>

| 비교 항목 | 전통 IPsec/SSL VPN (망 단위 접근) | 제로 트러스트 네트워크 접근 (ZTNA) | 리버스 웹 프록시 (Reverse Proxy) |
|:---|:---|:---|:---|
| **접근 통제 단위** | **사내 서브넷 전체 (L3/L4 네트워크)** | **승인된 개별 애플리케이션 (L7 서비스)** | 단일 웹 서버 (HTTP/HTTPS URL) |
| **인프라 외부 노출** | **VPN 게이트웨이 IP/포트 상시 개방** | **다크 IP (인바운드 포트 0개, 완전 은닉)** | **웹 서버 공인 IP/포트 외부 노출** |
| **측면 이동(Lateral) 방어**| **전혀 불가 (내부망 전체 횡적 확산)** | **완벽 차단 (1:1 마이크로 세그먼테이션)**| 부분 가능 (웹 서버 침해 시 내부망 확산) |
| **단말 무결성 검증** | 초기 연결 시 1회 검증 (상시 감시 불가) | **세션 유지 중 실시간 지속 평가 (EDR 연동)**| 없음 (단순 웹 브라우저 접속) |
| **적용 권장 환경** | 레거시 전체망 관리자 전용 | **전사 원격/재택근무 및 멀티 클라우드 접속**| 대고객 웹 서비스 공개 |

#### 한줄 요약
- VPN은 망 전체 개방 및 횡적 확산 위험, ZTNA는 L7 앱 1:1 격리 및 인프라 은닉 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Agent-based ZTNA vs Agentless ZTNA**:
  - **Agent-based**: 단말에 에이전트를 설치하여 EDR 연동 및 SSH/RDP/웹 등 모든 프로토콜 지원 (강력한 보안).
  - **Agentless**: 브라우저 기반으로 웹(HTTP/HTTPS) 앱에만 접근 지원 (외주 협력사 단말 등에 유연).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 사내 사무실 출근자가 ZTNA 검증을 우회하여 **내부망 스위치를 통해 타깃 서버에 직접 접근하는 보안 사각지대** | **사내 방화벽 및 스위치 ACL에서 사용자 단말의 서버 직접 접근을 전면 차단하고 상시 ZTNA 경유 강제** | 온프레미스/재택 구분 없는 일관된 제로 트러스트 검증 및 전사 트래픽 가시성 100% 확보 |
| 사내망에 배치된 ZTNA 커넥터 단일 노드 고장 시 **전사 원격근무자의 해당 업무 시스템 접근이 전면 마비** | **사내 및 클라우드 VPC 영역별 다중 커넥터(Multi-Connector) 액티브-액티브 HA 클러스터링 구성** | 단일 장애점(SPOF) 해소 및 로드밸런싱을 통한 99.999% 무중단 서비스 가용성 보장 |
| 복잡한 레거시 프로토콜(VoIP, Mainframe)을 사용하는 사내 시스템의 **ZTNA 전환 불가로 인한 프로젝트 난항** | **웹/클라우드 앱은 ZTNA로 즉시 전환하고, 레거시는 마이크로 세그먼테이션된 VPN을 병행하는 단계적 전환** | 업무 마비 없는 안정적인 CISA ZTMM 2.0 기반 순차적 마이그레이션 달성 |

#### 한줄 요약
- 모든 접근을 커넥터 한 점으로 모은 대가로 커넥터가 새로운 단일 장애점이 되므로, 다중화가 없으면 은닉으로 얻은 안전이 그대로 가용성 손실로 되돌아온다.
