## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **제로 트러스트 네트워크 접근(Zero Trust Network Access, ZTNA)**: 검증된 주체와 기기에 승인된 애플리케이션 연결만 제공하는 기술이다.
- **가상 사설망(Virtual Private Network, VPN)**: 암호화 터널로 원격 장비를 내부망에 연결하는 기술이다.
- **측면 이동**은 침해한 장비가 내부의 다른 자원으로 공격 범위를 넓히는 행위다.

</details>

- 정의/개념: 검증된 주체를 승인 앱에만 연결하는 **앱 단위** **접근 제어**이다.
- 배경/필요성: VPN의 넓은 내부망 노출로 **측면 이동 허용**이 필요하다.

#### 한줄 요약

- 원격 사용자를 내부망 전체에 넣지 않고 검증된 사용자에게 승인된 앱 하나로 가는 임시 통로만 연다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **앱 단위 접근**: 사용자 신원과 기기 상태를 검증해 내부망 전체가 아닌 승인된 애플리케이션 세션만 제공하는 방식이다.
- **기원 서버 비공개**: 내부 앱 커넥터의 발신 연결을 사용하여 실제 애플리케이션 서버를 외부에 노출하지 않는 구조이다.

</details>

- **앱 단위 접근**: 신원•기기 상태별 허용 앱을 제한한다.
- **기원 서버 비공개**: 내부 커넥터의 발신 연결 사용이다.
- **최소 노출**: 승인된 앱과 세션만 동적을 연결한다.

#### 한줄 요약

- ZTNA는 앱 문 앞까지만 안전하게 데려가므로 앱 안에서 어떤 데이터와 기능을 쓸지는 다시 확인해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **정책 브로커**: 신원•기기•위험 정보를 평가하여 애플리케이션 연결의 허용•거부를 결정하는 구성요소이다.
- **앱 커넥터**: 내부에서 ZTNA 서비스로 연결해 승인된 비공개 앱 세션을 중계하는 구성요소이다.

</details>

```text
[ZTNA]
   |
   +-- [사용자•기기]
   +-- [정책 브로커•신호]
   +-- [앱 커넥터]
   +-- [비공개 앱]
   `-- [로그•가용성]
```

선의 의미: 접근 주체•정책 판단•앱 중계•보호 자원•운영 통제의 정적 구성을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **사용자•기기** | 앱 요청과 **단말 상태 제공** |
| **정책 브로커•신호** | 접근 정책•신원•**위험 평가** |
| **앱 커넥터** | 승인 세션의 **내부 앱 중계** |
| **비공개 앱** | 외부에 숨긴 **보호 자원** |
| **로그•가용성** | 연결 추적과 **장애 대응** |

#### 한줄 요약

- 브로커가 사용자와 기기 신호를 확인해 승인하면 내부 커넥터가 외부에 드러나지 않은 앱으로만 연결한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **제한 세션**은 허용된 앱•행위•시간 범위로만 유지되는 연결이다.
- **연결 로그**는 사용자•기기•앱•허용 결과를 접속 증적으로 기록한 자료다.
- **위험 신호 환류**: 세션 행위와 기기 상태의 변화를 정책 브로커에 되돌려 재인증•제한•종료를 판단하게 하는 과정이다.

</details>

```text
[사용자•기기]
      |
      `-- 대상 앱 접근 요청
                |
                v
[정책 브로커]
      |
      v
1. 신원•기기•위험 정책 판정
      |
      v
2. 제한 세션 정책 생성
      |
      v
[앱 커넥터]
      |
      v
3. 발신 커넥터•앱 터널 설정
      |
      v
[비공개 앱] -- 앱 응답
      |
      v
+----------------------------------+
| 세션 유지 중                     |
|                                  |
|  4. 세션 행위•연결 로그 수집     |
|             |                    |
|             v                    |
|       [정책 브로커]              |
|             |                    |
|             v                    |
|  5. 세션 위험 재평가             |
|             |                    |
|             `-- 유지•제한•종료   |
+----------------------------------+
      |
      `-- 접근 결과 ----> [사용자•기기]
```

**동작 원리**

- **1. 신원•기기•위험 정책 판정**: 허용 조건•재인증을 결정한다.
- **2. 제한 세션 정책 생성**: 앱•행위•시간 범위를 최소화이다.
- **3. 발신 커넥터•앱 터널 설정**: 기원 서버를 숨긴 전용 연결을 생성한다.
- **4. 세션 행위•연결 로그 수집**: 승인 세션과 우회 접속 증적을 기록한다.
- **5. 세션 위험 재평가**: 조건 변경 시 유지•제한•종료를 판정한다.
#### 한줄 요약

- 사용자가 앱을 요청할 때마다 정책을 확인하고 승인된 경우에만 커넥터가 그 앱으로 가는 짧고 좁은 통로를 만든다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **앱 프록시**는 외부 요청을 특정 웹 애플리케이션으로 중계하는 접근 구성요소다.

</details>

| 원격 접근 방식 | ZTNA | 전통 VPN | 애플리케이션 프록시 |
|:---|:---|:---|:---|
| 적용 기준 | 앱별 **최소 접근** | 넓은 **내부망 원격 접속** | 웹 앱 중심의 **외부 공개** |
| 핵심 특징 | **앱•세션별 동적 연결** | **원격 장비 내부망 연결** | 특정 웹 앱 요청 중계 |
| 한계 | **신호•커넥터•중앙 장애** | **내부 탐색•측면 이동** | **비웹 한계•직접 우회** |

#### 한줄 요약

- VPN은 망에 들어가는 통로이고 앱 프록시는 주로 웹을 중계하며 ZTNA는 신원과 기기를 보고 앱별 통로를 동적으로 연다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST(National Institute of Standards and Technology)**는 미국의 기술 표준과 지침을 개발하는 기관이다.
- **SP(Special Publication) 800-207**은 제로 트러스트의 논리 구성과 배치 모델을 정의한다.
- **CISA(Cybersecurity and Infrastructure Security Agency)**는 미국의 사이버 보안•기반시설 보호 기관이다.
- **ZTMM(Zero Trust Maturity Model) 2.0**은 도메인별 제로 트러스트 전환 성숙도를 제시한다.
- **다중 커넥터**는 앱 중계 구성요소를 이중화해 단일 장애를 방지하는 구성이다.
- **직접 경로 차단**은 ZTNA를 우회한 기원 서버 접속을 네트워크에서 거부하는 통제다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **정책•집행 책임 혼선** | **NIST SP 800-207 적용** | 앱별 결정•세션의 **책임 정렬** |
| **단계적 VPN 전환 지연** | **CISA ZTMM 2.0 활용** | 중요 앱 중심의 **전환 측정** |
| **커넥터 장애•직접 우회** | **다중 커넥터•기원 접근 차단** | 가용성과 **최소 노출 확보** |

#### 한줄 요약

- ZTNA는 협력사 사용자의 신원과 기기 상태를 확인한 뒤 계약 업무 앱에만 연결하고 내부망 주소나 다른 서비스는 노출하지 않는다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

</details>

- 승인 앱 최소 접근은 **ZTNA**, 넓은 레거시 망은 **VPN**, 웹 공개는 **앱 프록시**가 핵심이다.

#### 한줄 요약

- ZTNA는 내부망 입장권 없이 필요한 앱만 연결하며 직접 경로와 앱 내부 권한도 따로 통제한다.
