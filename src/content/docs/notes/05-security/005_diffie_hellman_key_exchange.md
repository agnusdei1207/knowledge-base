## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DH 키 교환 (Diffie-Hellman Key Exchange)**: 서로 만난 적 없는 두 사람이 도청자가 우글거리는 인터넷(공개망)에서 암호키의 '재료'만 팩트로 주고받아, 각자 집에서 똑같은 비밀키를 뚝딱 만들어내는 수학적 마술이다.
- **공유 비밀 (Shared Secret)**: 통신 양단이 합의하여 도출한 똑같은 팩트 대칭키다.

</details>

- 정의: 비밀키를 통째로 던지지 않고, 계산된 공개값 교환만으로 동일한 **공유 비밀**을 안전하게 합의하는 **DH 키 합의** 팩트 기술이다.
- 배경: 대칭키를 네트워크로 직접 던지면 도청자에게 100% 털리는 **통신 경로 직접 전송 위험** 때문에, 키를 안전하게 합의할 수학적 우회로가 필요했다.

#### 한줄 요약

- 열쇠를 던져주지 않고 "열쇠 만드는 레시피 일부"만 교환해서, 해커가 지켜보는 와중에도 둘만 아는 똑같은 열쇠를 팩트로 만들어낸다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **순방향 비밀성 (Perfect Forward Secrecy, PFS)**: 매번 통신할 때마다 DH 키 재료를 새로 만들고 버림으로써, 나중에 서버가 털려도 과거 데이터는 절대 팩트로 못 풀게 만드는 성질이다.
- **중간자 공격 (MITM, Man-In-The-Middle)**: DH 키 교환은 "이게 내 공개값이야"라고 던지는데, 중간에 해커가 가로채서 자기 공개값으로 바꿔치기하는 치명적인 취약점이 있다.

</details>

- **팩트 키 합성**: 비밀키를 절대 네트워크에 태우지 않고, 모듈러 수학 연산으로 각자 똑같은 **공유 비밀**을 팩트로 도출한다.
- **팩트 일회용 키 (순방향 비밀성)**: 세션마다 1회용 개인값을 만들어 쓰는 DHE 방식으로 과거 데이터의 유출을 원천 차단한다.
- **치명적 맹점 (중간자 공격 취약성)**: 상대방 신원을 확인하지 않고 수학 합의부터 하므로, 서명(PKI)이 결합되지 않으면 **MITM**에 무조건 털린다.

#### 한줄 요약

- 키 유출 방어와 일회용 키(PFS) 생성엔 탁월하지만, "저놈이 진짜 은행 맞나?"를 팩트 증명하는 인증 기능이 아예 없다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **도메인 매개변수 (p, g)**: 키 합의를 하기 전 양쪽이 "우리 이 소수(p)랑 이 숫자(g)를 기준으로 수학 계산하자"고 팩트로 맞추는 베이스캠프다.
- **KDF (키 유도 함수)**: 공유 비밀을 믹서기에 돌려서 실제 암호화에 쓸 수 있는 예쁜 길이의 팩트 세션키로 뽑아내는 함수다.

</details>

```text
[ 디피-헬만 팩트 키 합의 구조 ]

[ 1. 도메인 매개변수 합의 ] ── (큰 소수 p와 생성원 g라는 수학적 베이스캠프를 팩트로 정함)
      │
      ▼
[ 2. 임시 키 쌍 생성 ] ── (각자 나만의 1회용 난수(개인값)를 뽑고, p/g와 섞어서 공개값을 만듦)
      │
      ▼ (공개값 교환)
[ 3. 공유 비밀 계산 ] ── (받은 상대 공개값에 내 개인값을 섞으면 기적처럼 양쪽 값이 똑같아짐)
      │
      ▼
[ 4. KDF (키 유도 함수) ] ── (만들어진 거친 공유 비밀을 팩트 세션키로 정제함)
```

| 구성요소 | 팩트 폭행 책임 | 비고 |
|:---|:---|:---|
| **도메인 매개변수 (p, g)** | 키 합의의 바탕이 되는 **수학적 공식(소수와 생성원)을 팩트로 제공함** | Parameters |
| **임시 키 쌍 생성부** | 절대 안 까발릴 **나만의 1회용 개인값과, 상대한테 던질 공개값을 굽는 곳** | Key Gen |
| **공유 비밀 계산 모듈** | 상대 공개값 + 내 개인값으로 **똑같은 대칭키 재료를 팩트로 뽑아내는 수학 엔진** | DH Engine |
| **KDF (키 유도 함수)** | 거친 공유 비밀을 **실제 암호화에 쓸 수 있게 예쁘게 다듬어주는 팩트 믹서기** | KDF |

#### 한줄 요약

- 매개변수 정하고 $\to$ 각자 난수 섞어 값 던지고 $\to$ 상대 값에 내 난수 섞어서 $\to$ 마법처럼 똑같은 키를 도출한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **서명 검증**: 쌩으로 DH 공개값만 보내면 해커가 바꿔치기하니까, "이 공개값 진짜 내 거임!" 하고 공인인증서(PKI)로 전자서명을 팩트 첨부하는 방어 로직이다.

</details>

```text
[ DHE 기반 팩트 키 합의 및 MITM 차단 십자포화 흐름 ]

┌──────────────────────────────┐
│ 1. [임시 개인값 생성 및 공개값 연산]
│ (Alice와 Bob이 각자 난수 a, b를 뽑고, g^a와 g^b를 팩트로 연산함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 2. [전자서명 첨부 및 공개값 교환]
│ (가짜 방지를 위해 "이 공개값 진짜 내 거임!" 하고 서명(PKI)을 덧붙여 전송함)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 3. [상대 서명 검증 및 공유 비밀(g^ab) 계산]
│ (상대방 공개값이 찐인지 팩트 체크 후, 내 개인값 a를 섞어서 g^ab 만듦)
└──────────────┬───────────────┘
               ▼
┌──────────────────────────────┐
│ 4. [KDF 세션키 도출 및 통신 시작]
│ (양쪽 다 똑같이 도출된 g^ab를 믹서기(KDF)에 넣고 팩트 세션키 뽑아서 씀)
└──────────────────────────────┘
```

### 동작 원리

1. 임시 키쌍 연산: 검증된 도메인 매개변수 위에서 세션별 일회용 개인값과 공개값을 생성함.
2. 서명 및 교환: 공개값에 전자서명을 붙여 MITM을 방어하며 상대에게 팩트 전송함.
3. 공유 비밀 도출: 서명 검증 통과 후, 상대 공개값에 내 개인값을 연산해 똑같은 비밀을 계산함.
4. KDF 세션키 정제: 계산된 공유 비밀을 KDF로 밀어 넣어 본문 암호화용 세션키로 파생시킴.

#### 한줄 요약

- 공개값을 던질 때 전자서명 씰을 팩트로 붙여서, 해커가 중간에서 가짜 값을 끼워 넣지 못하게 원천 차단한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 DH**: 한 번 정한 개인값을 평생 쓰는 낡은 방식. 털리면 과거 데이터 다 풀린다.
- **DHE (임시)**: 매 세션마다 개인값을 새로 뽑아 쓰는 순방향 비밀성(PFS)의 교과서다.
- **ECDHE (타원곡선 임시)**: 무거운 소수 계산 대신 가벼운 타원곡선 알고리즘을 섞어서, 빠르고 팩트 튼튼하게 만든 최신 규격이다.

</details>

| DH 키 교환 방식 | **정적 DH (Static DH)** | **DHE (임시 DH)** | **ECDHE (타원곡선 임시 DH)** |
|:---|:---|:---|:---|
| 팩트 폭행 비유 | **한 번 정한 비번 평생 쓰는 '구식 도어락'** | **매번 비번이 바뀌지만 '무겁고 큰 금고'** | **가볍고 빠르면서 매번 바뀌는 '최신 스마트락'** |
| 핵심 기술 원리 | 장기적인 고정 개인값을 계속 팩트로 재사용해서 공유 비밀 만듦 | 세션마다 새로운 유한체 개인값을 생성해 **순방향 비밀성(PFS) 보장** | 타원곡선(ECC) 알고리즘을 결합해 적은 키 길이로 **초고속 DHE 구현** |
| 최고 장점 | 시스템 부하가 적고 **과거 호환성이 팩트로 뛰어남** | 내일 장기키 털려도 옛날 데이터는 안전한 **'순방향 비밀성' 확보** | DHE보다 연산량이 훨씬 적어서 **모바일이나 TLS 환경에 팩트 찰떡임** |
| 치명적 한계 | 장기키 하나 털리면 **과거 통신 데이터까지 싹 다 풀림(PFS 미보장)** | 큰 매개변수(소수) 처리로 **연산 오버헤드(비용)가 심함** | 곡선 검증 안 하면 해커가 조작된 곡선 줘서 털어먹을 수 있음 |

#### 한줄 요약

- 옛날 정적 DH는 팩트 폐기 수준이고, 현재 인터넷 보안(TLS)의 국룰은 빠르고 안전한 ECDHE다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **FFDHE (RFC 7919)**: 해커가 풀기 쉬운 구린 소수(p)를 못 쓰게, IETF 표준에서 "이 소수 그룹만 써라!" 하고 팩트 도장 찍어준 안전 그룹이다.
- **X25519 (RFC 7748)**: 구현하다가 삑사리 나기 쉬운 타원곡선 식을, 아예 공식으로 예쁘게 팩트 표준화해 놓은 고속 알고리즘이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| 해커가 중간에서 **공개값을 팩트로 바꿔치기함 (MITM 공격)** | DH 자체에는 상대방이 찐인지 확인하는 신원 인증 기능이 아예 없음 | DH 공개값 교환 전/후에 **PKI 인증서 기반 전자서명(TLS) 팩트 결합** | 중간자의 통신 가로채기(MITM) 및 사칭 공격 원천 봉쇄 |
| 임의로 만든 구식 수학 공식 썼다가 **0.1초 만에 풀려버림** | 크기가 작거나 소수 조건이 부실한 도메인 매개변수(p, g)를 대충 씀 | **IETF RFC 7919 (FFDHE)** 에서 검증된 팩트 안전 그룹만 강제 사용 | 소분군 공격 및 불량 매개변수로 인한 암호키 역산(털림) 방어 |
| 벤더별 타원곡선 구현 오류로 **통신이 자꾸 팩트 끊김** | 벤더마다 곡선 계산 방식이 다르고 보안 검증 로직을 빼먹음 | 검증된 고속 타원곡선 표준인 **RFC 7748 (X25519)** 팩트 도입 | 구현 오류로 인한 호환성 문제 해결 및 암호화 성능 극대화 |

#### 한줄 요약

- DH는 신원 인증(PKI 서명)과 검증된 팩트 매개변수(RFC 7919) 그룹을 섞지 않으면 속 빈 강정일 뿐이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- (상단 참조)

</details>

- 통신 경로의 대칭키 유출을 원천 차단하기 위해 비밀값을 보내지 않는 **DH 연산**을 수행하고, 서명 기반 **MITM 차단**과 **ECDHE(순방향 비밀성)** 를 결합한 안전한 키 합의 팩트 기조 확립함

#### 한줄 요약

- 키를 넘겨주지 않고도 똑같은 열쇠를 갖게 만드는 DH의 마술은, PKI 서명이라는 팩트 보안관이 있어야만 완성된다.
