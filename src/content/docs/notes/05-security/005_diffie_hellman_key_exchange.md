## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Diffie-Hellman Key Exchange (DH, 디피-헬만 키 교환)**: 안전하지 않은 채널에서 사전 비밀키 없이 공개값 교환만으로 동일한 대칭키를 도출하는 키 합의 알고리즘.
- **Discrete Logarithm Problem (이산대수 문제, DLP)**: $Y = g^X \bmod p$에서 $p, g, Y$가 주어졌을 때 지수 $X$를 역산하는 것이 수학적으로 불가능한 난제.

</details>

- 정의/개념: 공개값 교환으로 공유 비밀을 도출하는 **디피-헬만 키 교환** 프로토콜
- 배경/필요성: 네트워크를 통해 비밀키를 직접 전송하는 방식은 전송 구간 도청 시 통신 전체의 기밀성이 즉시 붕괴되는 치명적인 위험을 안고 있으며, 사전에 비밀키를 대면 공유하는 방식은 전 세계 수십억 인터넷 사용자와 서버 간의 동적 통신 환경에서 물리적으로 불가능한 한계를 가짐에 따라, 도청자가 도청 가능한 공개 채널 상에서 양단이 각자의 임시 비밀 난수와 공개 파라미터를 교환한 후 **이산대수 문제**(DLP) 또는 타원곡선 이산대수(ECDLP)의 수학적 일방향 난제를 활용하여 양측이 독립적으로 동일한 대칭 세션키를 계산해내는 디피-헬만(Diffie-Hellman) 키 합의 프로토콜을 도입하여 사전 비밀 공유 없는 안전한 세션키 도출, 세션별 일회용 임시 키(ECDHE) 사용을 통한 순방향 비밀성(PFS: Perfect Forward Secrecy) 확보 및 개방형 인터넷 보안 통신의 토대 마련을 달성할 필요

#### 한줄 요약
- 이산대수 난제와 공개값 교환을 통해 비밀키 전송 없이 안전한 대칭 세션키를 양단에서 합의한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ECDHE (Elliptic Curve DHE)**: 유한체 지수 연산 대신 타원곡선 스칼라 곱셈($Q = d \cdot G$)을 사용하여 256비트 키로 초고속 키 합의를 수행하는 현대 표준.
- **MITM Vulnerability (중간자 취약점)**: DH 자체에는 인증(Authentication) 메커니즘이 없어 단독 사용 시 중간자 공격에 노출되므로 전자서명 결합이 필수적인 특성.

</details>

- 비밀값을 보내지 않는 공개값 기반 키 합의
- 임시 키 폐기 시 순방향 비밀성 제공
- **ECDHE**·**X25519** 기반 작은 키와 효율적 연산

#### 한줄 요약
- 키를 보내지 않는 대신 상대가 누구인지 확인할 근거도 함께 사라지므로, DH는 기밀성만 담당하고 신원 확인은 전자서명·PKI 계층에 반드시 위임해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Domain Parameters ($p, g$)**: 유한체 모듈러 연산의 기준이 되는 2048비트 이상 안전한 소수($p$)와 원시근 생성원($g$).

</details>

```text
Diffie-Hellman
|-- Domain Parameters
|-- Ephemeral Private Values
|-- Public Values
|-- Signature Engine
`-- HKDF Module
```

선의 의미: Alice와 Bob이 각각 임시 난수를 뽑아 공개값을 계산하고 전자서명을 첨부하여 상호 교환한 후 양단에서 동일한 $g^{ab} \bmod p$를 도출하는 구조

| 구성요소 | 책임 |
|:---|:---|
| **Domain Parameters** | 유한체·곡선 연산 기준 제공 |
| Ephemeral Private Values | 세션별 비공개 난수 제공 |
| Public Values | 상대와 교환할 좌표 제공 |
| Signature Engine | 공개값과 신원 결합 |
| HKDF Module | 공유 비밀에서 세션키 도출 |

#### 한줄 요약
- 개인값을 세션마다 버리는 임시 계층이 장기 개인키와 세션키의 연결을 끊어 주므로, 장기키 유출의 피해 범위가 과거 세션 전체에서 현재 세션 하나로 줄어든다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Curve25519 (X25519, RFC 7748)**: 몽고메리 곡선 상에서 타이밍 부채널 공격에 면역이며 극도로 빠른 스칼라 곱셈 연산을 제공하는 표준 타원곡선.

</details>

```text
ECDHE 타원곡선 파라미터 합의, 좌표 연산 및 공유 비밀 도출 파이프라인
        │
   1. [곡선 파라미터 합의]
        │
   2. [임시 개인값 생성]
        │
   3. [공개 좌표 산출]
        │
   4. [서명된 공개 좌표 교환]
        │
   ▼
   5. [공유 비밀 및 세션키 도출]
```

- 1. 곡선 파라미터 합의
- 2. 임시 개인값 생성
- 3. 공개 좌표 산출
- 4. 서명된 공개 좌표 교환
- 5. 공유 비밀 및 세션키 도출

#### 한줄 요약
- 공개 좌표에 서명이 붙는 4단계가 전 구간의 신뢰를 가르는 지점으로, 이 서명이 빠지면 이후 단계가 아무리 정확해도 중간자와 정상 상대를 구분할 수 없다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **FFDHE (Finite Field DHE, RFC 7919)**: 서버가 임의 소수를 고르지 못하게 2048~8192비트 표준 소수 그룹(ffdhe2048 등)을 미리 고정한 TLS 유한체 DH 그룹 목록으로, 검증되지 않은 약한 소수 사용과 그 소수에 대한 사전 계산 공격을 막음.

</details>

| 비교 항목 | 정적 DH (Static DH) | 임시 유한체 DH (DHE / FFDHE) | 타원곡선 임시 DH (ECDHE) |
|:---|:---|:---|:---|
| 수학적 기반 | 유한체 DLP | 유한체 DLP | 타원곡선 ECDLP |
| 개인값 수명 | 장기 재사용 | 세션별 생성·폐기 | 세션별 생성·폐기 |
| 순방향 비밀성 | 미지원 | 임시 키 폐기 시 지원 | 임시 키 폐기 시 지원 |
| 키 크기·연산 | 장기 유한체 키 | 큰 유한체 매개변수 | 작은 곡선 키 |
| 적용 | 레거시 환경 | RFC 7919 **FFDHE** | TLS 1.3 **ECDHE** |

#### 한줄 요약
- 정적 DH는 PFS 미지원으로 폐기되었으며, DHE는 연산이 무겁고, ECDHE(X25519)가 현대 초고속 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Logjam (Logjam Attack)**: 1024비트 이하의 취약한 공용 소수 매개변수를 사용하는 DH 서버에 대해 사전 연산 테이블로 실시간 이산대수를 해독하는 공격.
- **Invalid Curve (비유효 곡선 공격)**: 공격자가 정상 곡선 위에 있지 않은 점을 공개값으로 보내 상대가 검증 없이 스칼라 곱을 수행하면 작은 부분군에서 개인키 조각이 새어 나오는 공격으로, 수신한 점이 곡선 방정식을 만족하는지 검사해야 막힘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 인증 없는 공개값의 **중간자 취약점** | PKI 기반 서명 검증 | 공개값과 신원 결합 |
| 약한 DH 그룹의 **Logjam** | RFC 7919 **FFDHE** 또는 **X25519** | 검증된 매개변수 사용 |
| 비표준 곡선의 **Invalid Curve** | P-256·**X25519** 제한 | 곡선 입력 위험 완화 |
| SNDL 양자 위협 | ECDHE와 ML-KEM 하이브리드 | 고전·PQC 위험 분산 |

#### 한줄 요약
- DH의 사고는 수학이 아니라 입력에서 나므로, 상대가 보낸 공개값과 그룹 파라미터를 검증 없이 받아들이는 순간이 실무 위험의 전부다.

## Ⅶ. 결론

- 공개 채널을 통해 비밀을 직접 전송하지 않고도 양단 간에 완벽한 대칭 세션키를 계산해내는 획기적인 발상으로 공개키 암호학의 시대를 연 현대 인터넷 보안 통신(TLS 1.3 / SSH / IPsec)의 가장 핵심적인 키 합의 프로토콜 표준 기술로 확고히 자리 잡았으며, 양자 컴퓨터의 Shor 알고리즘 공격에 대응하는 격자 기반 양자내성 KEM(ML-KEM-768)과의 하이브리드 결합으로 진화하는 가운데, 실무 디피-헬만 프로토콜 구현 시에는 자체 인증 기능 부재에 따른 중간자 공격(MITM)을 원천 차단하기 위한 X.509 PKI 전자서명 결속, 서버 장기 개인키 유출 시에도 과거 통신을 안전하게 보호하는 임시 타원곡선 키 교환(ECDHE: X25519 / P-256) 기반 완벽한 순방향 비밀성(PFS) 보장, 약한 소수 파라미터 공격(Logjam)을 방지하는 검증된 표준 그룹(RFC 7919 FFDHE) 적용을 결합하여 완벽한 키 합의 무결성을 완성

#### 한줄 요약
- 키 교환은 항상 임시(Ephemeral)로 쓰고 서명으로 상대를 묶는 것이 기본형이므로, 정적 DH나 서명 없는 DH는 선택지에서 제외한다.
