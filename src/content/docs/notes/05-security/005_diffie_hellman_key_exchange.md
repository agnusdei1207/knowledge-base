## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **디피-헬만 키 교환(Diffie-Hellman Key Exchange, DH / RFC 2631)**: 안전하지 않은 공용 네트워크(Insecure Public Channel) 상에서 두 통신 당사자가 사전 공유 비밀키 없이도, 공개된 도메인 매개변수와 각자의 비밀 난수를 조합한 수학적 계산을 통해 동일한 대칭 비밀키(Shared Secret)를 안전하게 도출하는 키 합의(Key Agreement) 알고리즘.
- **이산대수 문제(Discrete Logarithm Problem, DLP)**: 유한체(Finite Field) 상에서 소수 $p$와 생성원 $g$, 그리고 $Y = g^X \bmod p$가 주어졌을 때, $Y$로부터 비밀 지수 $X$를 역산하는 것이 계산 복잡도 상 극도로 어려운 수학적 난제.

</details>

- 정의/개념: 평문 비밀키를 네트워크로 직접 전송하지 않고 각자의 공개값($A = g^a \bmod p$, $B = g^b \bmod p$)만을 교환하여, 모듈러 지수 법칙($g^{ab} \bmod p$)을 통해 양단이 동일한 **공유 비밀(Shared Secret)** 을 독립 계산하는 **대칭키 합의 암호 프로토콜**
- 배경/필요성: 대칭키 암호화의 근본적 취약점인 도청 가능한 네트워크 상에서의 비밀키 직접 전송 위험(Key Transmission Problem)을 수학적으로 극복할 요구

#### 한줄 요약
- 이산대수 난제를 활용하여 비밀키 전송 없이 공개값 교환만으로 동일한 공유 비밀을 안전하게 합의한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **에페머럴 DH(Ephemeral Diffie-Hellman, DHE / ECDHE)**: 정적(Static) 키를 장기간 재사용하지 않고, 매 세션 핸드셰이크마다 1회용 임시 비밀값($a, b$)을 생성하고 세션 종료 즉시 메모리에서 폐기하여 **순방향 비밀성(PFS)** 을 완벽 보장하는 방식.
- **중간자 공격(Man-in-the-Middle, MITM)**: DH 키 교환 자체에는 상대방의 신원을 검증하는 인증 메커니즘이 없어, 공격자가 중간에서 공개값을 가로채고 자신의 가짜 공개값으로 바꿔치기하여 양단과 각각 독립된 키를 수립하는 취약점.

</details>

- **네트워크 비노출 대칭키 합성**: 양단의 비밀값($a, b$)은 절대 송출되지 않으며, 도청자는 공개된 $g^a, g^b$만으로 $g^{ab}$를 도출 불가
- **순방향 비밀성(PFS) 네이티브 지원 (DHE/ECDHE)**: 장기 개인키가 유출되어도 과거 수집된 패킷 트래픽의 세션키 복원 불가
- **인증 결합 필수성 (PKI / Digital Signature)**: MITM 공격을 방어하기 위해 반드시 X.509 인증서 전자서명과 결합하여 운영 (TLS 1.3 표준)

#### 한줄 요약
- 비밀키 비전송 합성, DHE/ECDHE 기반 순방향 비밀성, PKI 전자서명 결합을 통한 MITM 방어를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **도메인 매개변수(Domain Parameters: $p, g$)**: DH 연산의 기반이 되는 안전한 큰 소수 $p$(통상 2048비트 이상)와 승법군의 생성원 $g$.

</details>

```text
[ 송신자: Alice ]                                                  [ 수신자: Bob ]
 ├─ 비밀 개인값 생성: $a$ (1회용 임시 난수)                           ├─ 비밀 개인값 생성: $b$ (1회용 임시 난수)
 ├─ 공개값 연산: $A = g^a \bmod p$                                  ├─ 공개값 연산: $B = g^b \bmod p$
 └─ 개인키로 전자서명: $\text{Sign}(A)$                              └─ 개인키로 전자서명: $\text{Sign}(B)$
           │                                                                   ▲
           ▼ (1. Alice의 공개값과 서명 전송: $A \parallel \text{Sign}(A)$)     │
┌──────────────────────────────────────────────────────────────────────────────┼───────────────────┐
│ [ 공용 네트워크 (Public Insecure Channel) ]                                   │                   │
│  ├─ 도청자(Eve)는 도메인 파라미터 $(p, g)$와 공개값 $(A, B)$만 관측 가능      │                   │
│  └─ 이산대수 난제로 인해 $a, b$ 및 $g^{ab} \bmod p$ 계산 불가               │                   │
│                                                                              │                   │
│          (2. Bob의 공개값과 서명 회신: $B \parallel \text{Sign}(B)$) ────────┘                   │
│                ▼                                                             │
└────────▶ [ 서명 검증 후 공유 비밀 연산 ]                                     ▼
           $K = B^a \bmod p = (g^b)^a = g^{ab} \bmod p$          [ 서명 검증 후 공유 비밀 연산 ]
                                                                 $K = A^b \bmod p = (g^a)^b = g^{ab} \bmod p$
                                         │                                     │
                                         ▼                                     ▼
                      [ 양단 간 완전히 동일한 대칭 마스터 비밀 $K = g^{ab} \bmod p$ 확립 ]
```

선의 의미: Alice와 Bob이 각각 임시 난수를 뽑아 공개값을 계산하고 전자서명을 첨부하여 상호 교환한 후, 양단에서 동일한 $g^{ab} \bmod p$를 도출하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **도메인 매개변수 ($p, g$)** | 유한체 모듈러 연산의 기준이 되는 안전한 소수($p \ge 2048\text{bit}$) 및 생성원 | RFC 7919 FFDHE |
| **임시 개인값 ($a, b$)** | 각 당사자가 안전한 난수 생성기(CSPRNG)로 추출하여 외부에 비공개 보관하는 난수 | Ephemeral Key |
| **공개값 ($A, B$)** | $g^a \bmod p$, $g^b \bmod p$로 계산되어 네트워크를 통해 상대방에게 전송되는 값 | Public Exchange |
| **전자서명 엔진** | 공개값 위조 및 중간자 공격을 차단하기 위해 X.509 개인키로 전자서명 부착 | ECDSA / RSA-PSS |
| **HKDF 키 유도 모듈** | 도출된 거친 공유 비밀($g^{ab}$)로부터 대칭 암호화에 사용할 256비트 AES 세션키 추출 | RFC 5869 HKDF |

#### 한줄 요약
- 도메인 매개변수($p, g$), 임시 개인값($a, b$), 교환 공개값($A, B$), 전자서명 엔진, HKDF 모듈이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **타원곡선 디피-헬만(ECDHE, RFC 7748 / 8422)**: 모듈러 지수 연산 대신 타원곡선 상의 점 덧셈 및 스칼라 곱셈($Q_A = d_A \cdot G$)을 사용하여, 256비트 키 길이만으로 RSA 3072비트 급의 보안성과 10배 빠른 속도를 제공하는 고효율 키 교환 방식.

</details>

```text
1. 통신 당사자(Alice, Bob)가 사용할 표준 타원곡선 도메인 파라미터(예: Curve25519) 합의
            │
            ▼
2. Alice와 Bob이 각각 독립된 256비트 암호학적 임시 개인값($d_A, d_B$)을 무작위 생성
            │
            ▼
3. 타원곡선 기준점 $G$에 스칼라 곱을 수행하여 공개 좌표 $Q_A = d_A \cdot G$, $Q_B = d_B \cdot G$ 산출
            │
            ▼
4. 각자의 X.509 인증서 개인키로 서명한 후 공개키 좌표($Q_A, Q_B$) 상호 전송
            │
            ▼
5. 수신된 공개 좌표에 자신의 개인값을 곱셈($K = d_A \cdot Q_B = d_B \cdot Q_A = d_A d_B G$) ➔ 동일 세션키 완성
```

**동작 원리**

1. **파라미터 초기화**: NIST P-256 또는 Curve25519 표준 타원곡선 방정식 로드
2. **개인값 추출**: CSPRNG(암호학적 안전 난수 발생기)를 통해 256비트 스칼라 비밀값 생성
3. **공개점 연산**: 타원곡선 군(Group) 상에서 곱셈 연산으로 공개 좌표점 산출
4. **상호 서명 교환**: 상대방의 서명과 인증서를 검증하여 MITM 가짜 공개값 주입 차단
5. **공통 비밀 수렴**: 교환된 좌표에 자신의 스칼라를 곱하여 동일한 공유 좌표($X$-좌표) 획득

#### 한줄 요약
- 곡선 파라미터 합의, 임시 개인값 생성, 공개 좌표 산출 및 서명 교환, 스칼라 곱셈, 공통 세션키 수렴 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정적 DH vs DHE vs ECDHE**: 고정 키 재사용 방식, 유한체 임시 방식, 타원곡선 임시 방식의 성능 및 보안성 비교.

</details>

| 비교 항목 | 정적 DH (Static DH) | 임시 유한체 DH (DHE / FFDHE) | 타원곡선 임시 DH (ECDHE) |
|:---|:---|:---|:---|
| **수학적 기반** | 유한체 이산대수 ($g^a \bmod p$) | 유한체 이산대수 ($g^a \bmod p$) | **타원곡선 이산대수 ($d \cdot G$)** |
| **개인값 수명주기** | **고정 개인값 장기 재사용** | **세션마다 1회용 임시 생성 및 파기** | **세션마다 1회용 임시 생성 및 파기** |
| **순방향 비밀성 (PFS)**| **미지원 (서버 키 유출 시 전면 해독)**| **완벽 지원 (과거 데이터 안전)** | **완벽 지원 (과거 데이터 안전)** |
| **연산 속도 및 부하** | 중간 | **매우 느림 (2048bit+ 대용량 소수 연산)**| **극도로 빠름 (256bit 고효율 곡선 연산)**|
| **표준 권고 상태** | 폐기 권고 | 제한적 사용 (RFC 7919 그룹) | **글로벌 표준 (TLS 1.3 필수 암호 스위트)**|

#### 한줄 요약
- 정적 DH는 PFS 미지원으로 폐기되었으며, DHE는 연산이 무겁고, ECDHE(X25519)가 현대 초고속 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Logjam 공격 / 취약한 소수군(Weak DH Group)**: 과거 512비트/1024비트 수출용 암호(Export Cipher) 소수를 재사용하거나 안전하지 않은 소수를 채택한 서버에 대해, 공격자가 수 주간의 사전 연산을 거쳐 이산대수를 실시간 해독하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DH 공개값 교환 시 인증 부재로 인한 공격자의 **중간자 가로채기(MITM) 및 도청 사고** | **X.509 PKI 인증서 기반 상호 서명(TLS 1.3 ECDHE-ECDSA/RSA)** 강제 | 공개값 위변조 탐지 및 비인가 중간자 통신 개입 100% 원천 차단 |
| 1024비트 이하 취약한 정적 소수 매개변수 사용으로 인한 **Logjam 공격 및 키 복구** | **최소 2048비트 이상의 RFC 7919 FFDHE 안전 소수군 강제 또는 X25519 전환** | 소분군 공격 차단 및 이산대수 해독 계산 복잡도 $2^{128}$ 보증 |
| 비표준 커스텀 타원곡선 사용 시 공격자의 **악의적 매개변수 주입(Invalid Curve Attack)** | **NIST P-256(secp256r1) 및 RFC 7748 Curve25519(X25519)** 검증 곡선만 허용 | 곡선 파라미터 변조 공격 차단 및 상호운용성 완벽 확보 |

#### 한줄 요약
- PKI 서명으로 MITM을 방어하고, RFC 7919/X25519로 Logjam을 차단하며, 표준 곡선으로 파라미터 변조를 방지한다.

## Ⅶ. 결론

- 공개 네트워크 상에서 대칭 세션키를 안전하게 수립하기 위한 **디피-헬만(Diffie-Hellman) 키 교환 아키텍처**는 인터넷 보안 통신의 핵심 표준이며, 실무 구현 시 **ECDHE 기반 순방향 비밀성(PFS) 의무화**, **X.509 PKI 전자서명과의 결합을 통한 MITM 방어**, **미래 양자 컴퓨팅에 대응하는 ML-KEM 하이브리드 키 교환 전환**을 통합 구현하여 완결성 높은 안전한 키 합의 환경을 완성

#### 한줄 요약
- ECDHE와 PKI 전자서명 및 PQC 하이브리드를 결합하여 순방향 비밀성이 보장된 안전한 키 합의를 실현한다.
