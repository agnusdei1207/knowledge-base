## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **디피-헬만 키 교환(Diffie-Hellman Key Exchange, DH 키 교환)**: 비밀값을 직접 전송하지 않고 공개값만 교환하여 양측이 같은 공유 비밀을 계산하는 키 합의 방식이다.
- **DH 키 합의**: 공개값 교환과 각자의 개인값 계산으로 같은 공유 비밀을 얻는 합의 방식이다.
- **통신 경로 직접 전송 위험**: 대칭키 자체를 네트워크로 전달할 때 도청으로 키가 노출될 수 있는 위험이다.

</details>

- 정의/개념: **DH 키 교환**은 공개값 교환으로 같은 비밀을 계산하는 **DH 키 합의**이다.
- 배경/필요성: 대칭키의 **통신 경로 직접 전송 위험** 해소가 필요하다.

#### 한줄 요약

- 두 사람이 각자 숨긴 색을 공개된 색과 섞어 중간 결과만 교환하면, 숨긴 색을 보내지 않고도 같은 최종 색을 만들 수 있다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **공유 비밀**: 양측이 각자의 개인값과 상대 공개값으로 동일하게 계산하는 세션키의 원재료이다.
- **순방향 비밀성**: 연결마다 임시 개인값을 사용하여 장기키 유출 뒤에도 과거 세션키를 보호하는 성질이다.
- **중간자 공격**: 인증되지 않은 공개값을 공격자가 바꿔 양측과 각각 다른 비밀을 합의하는 공격이다.

</details>

- 비밀값을 전송하지 않고 **공유 비밀**을 합의한다.
- 임시 개인값의 **순방향 비밀성**이 핵심이다.
- 인증을 결합해 **중간자 공격**을 차단한다.

#### 한줄 요약

- DH 계산이 맞아도 공개값의 주인을 확인하지 않으면 공격자가 양쪽과 따로 비밀을 만들어 통신을 중계할 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **도메인 매개변수**: DH 계산에 사용할 그룹과 생성원 등 참여자가 공유하는 공개 설정이다.
- **개인값**: 참여자가 비밀로 생성하고 외부에 공개하지 않는 계산 입력이다.
- **공개값**: 개인값을 도메인 매개변수로 계산하여 상대에게 전달하는 값이다.
- **키 유도 함수(Key Derivation Function, KDF)**: 공유 비밀에서 용도와 통신 방향별 세션키를 생성하는 함수이다.
- **임시 키 생성기**: 세션마다 새로운 개인값과 공개값을 생성하는 구성요소이다.
- **공유 비밀 계산기**: 상대 공개값과 자신의 개인값을 결합해 공유 비밀을 계산하는 구성요소이다.

</details>

```text
DH 키 합의 구조
├─ 도메인 매개변수
├─ 임시 키 생성기
├─ 공유 비밀 계산기
└─ 키 유도 함수
```

가지의 의미: 매개변수•키 생성•비밀 계산•키 분리 책임을 나눈 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 도메인 매개변수 | **도메인 매개변수**가 검증된 그룹•생성원 제공 |
| 임시 키 생성기 | **임시 키 생성기**가 세션별 **개인값**•**공개값** 생성 |
| 공유 비밀 계산기 | **공유 비밀 계산기**가 상대 공개값•개인값 결합 |
| 키 유도 함수 | **KDF**가 공유 비밀에서 세션키 분리 |


#### 한줄 요약

- 공통 계산 규칙에서 각자 임시 비밀과 공개값을 만들고, 상대 공개값에 자기 비밀을 섞어 같은 결과를 만든 뒤 KDF가 실제 암호키로 나눈다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **공개값 검증**: 상대가 보낸 값이 선택한 안전한 그룹에 속하고 금지된 값이 아닌지 확인하는 검증이다.
- **협상 기록 인증**: 교환한 공개값과 알고리즘 선택을 실제 통신 상대의 신원에 결합하는 인증이다.
- **공유 비밀 계산**: 상대 공개값과 개인값으로 양측이 같은 비밀을 얻는 과정이다.
- **세션키 도출**: 공유 비밀을 KDF에 입력하여 용도•방향별 키로 분리하는 과정이다.
- **임시 키쌍 생성**: 안전한 그룹에서 세션별 개인값과 공개값을 만드는 단계이다.
- **공개값•기록 검증**: 상대 공개값의 그룹 적합성과 협상 기록의 인증을 확인하는 단계이다.

</details>

```text
1. 임시 키쌍 생성
        │
        └── 인증된 공개값 상호 교환
                    │
                    ▼
2. 공개값•기록 검증
        ├─ 실패: 키 합의 중단
        └─ 성공
             │
             ▼
     3. 공유 비밀 계산
             │
             ▼
     4. 세션키 도출
```

### 동작 원리

1. **임시 키쌍 생성**: 안전한 그룹에서 **임시 키쌍 생성**을 수행한다.
2. **공개값•기록 검증**: **공개값 검증**과 **협상 기록 인증**으로 **공개값•기록 검증**을 수행한다.
3. **공유 비밀 계산**: 상대 공개값과 개인값으로 **공유 비밀 계산**을 수행한다.
4. **세션키 도출**: KDF로 **세션키 도출**을 수행한다.


#### 한줄 요약

- 상대 공개값이 정한 그룹에 속하는지 확인하지 않으면 공격자가 결과 후보가 적은 값으로 유도해 공유 비밀을 추측할 수 있다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **정적 디피-헬만(Static Diffie-Hellman, 정적 DH)**: 장기 개인값을 재사용하는 DH 방식이다.
- **임시 디피-헬만(Diffie-Hellman Ephemeral, DHE)**: 연결마다 새로운 유한체 개인값을 사용하는 방식이다.
- **타원곡선 임시 디피-헬만(Elliptic Curve Diffie-Hellman Ephemeral, ECDHE)**: 연결마다 새로운 타원곡선 개인값을 사용하는 방식이다.

</details>

| DH 키 교환 방식 | **정적 DH** | **DHE** | **ECDHE** |
|:---|:---|:---|:---|
| 적용 기준 | 기존 정적 DH 호환 | TLS의 유한체 임시 합의 | 작은 키의 임시 합의 요구 |
| 핵심 특징 | 장기 DH 개인값 재사용 | 세션별 유한체 개인값 | 세션별 타원곡선 개인값 |
| 한계 | 장기키 유출 시 과거 노출 | 큰 매개변수 처리 비용 | 곡선•공개값 검증 누락 |

> 요약: 과거 세션 보호에는 DHE•ECDHE을 선택한다.

#### 한줄 요약

- 같은 개인값을 오래 쓰면 나중에 그 값이 새었을 때 과거 통신도 풀리지만, 연결마다 새 값을 만들고 버리면 과거 세션키 복구를 제한할 수 있다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **인터넷 기술 태스크포스(Internet Engineering Task Force, IETF)**: 인터넷 프로토콜 표준을 개발하는 조직이다.
- **의견 요청 문서(Request for Comments, RFC) 7919**: TLS에서 사용할 표준 유한체 그룹을 규정한 표준이다.
- **유한체 임시 디피-헬만(Finite Field Diffie-Hellman Ephemeral, FFDHE)**: 세션마다 유한체 기반 임시 개인값을 사용하는 키 합의 방식이다.
- **전송 계층 보안(Transport Layer Security, TLS)**: 통신 상대 인증과 전송 구간 보호를 제공하는 프로토콜이다.
- **인터넷 연구 태스크포스(Internet Research Task Force, IRTF)**: 장기 인터넷 기술 연구를 수행하는 조직이다.
- **RFC 7748**: X25519 함수와 공개값 인코딩 규칙을 규정한 표준이다.
- **X25519**: Curve25519를 사용하는 타원곡선 DH 함수이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 임의 유한체 그룹 | **IETF**의 **RFC 7919** **FFDHE** 적용 | 매개변수 공격 억제 |
| 곡선•공개값 구현 오류 | **IRTF**의 **RFC 7748** **X25519** 적용 | 상호운용성 확보 |
| **중간자 공격** | **TLS** 인증서•협상 기록 서명 | 상대 신원 보장 |

#### 한줄 요약

- TLS 인증서는 DH 계산을 대신하지 않고 임시 공개값이 실제 서버가 보낸 것인지 인증하며, ECDHE가 양쪽의 공유 비밀(Pre-Master Secret)을 도출한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **인증된 임시 키 합의**: 세션별 개인값으로 순방향 비밀성을 확보하고 인증서로 공개값의 실제 소유자를 확인하는 방식이다.
- **DH 키 교환 방식 선택**: 호환성•유한체 요구•키 크기와 순방향 비밀성에 따라 정적 DH•DHE•ECDHE를 결정하는 판단이다.

</details>

- **인증된 임시 키 합의**에서 유한체 호환은 **DHE**, 작은 키의 순방향 비밀성은 **ECDHE**를 택하는 **DH 키 교환 방식 선택**이 필요하다.

#### 한줄 요약

- 비밀값을 보내지 않는 수학만으로는 상대가 누구인지 알 수 없으므로, 임시값과 공개값 검증에 신원 인증을 결합해야 안전한 키 교환이 된다.
