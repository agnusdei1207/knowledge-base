## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **Diffie-Hellman Key Exchange (DH)**: 안전하지 않은 채널에서 사전 비밀키 없이 공개값 교환만으로 동일한 대칭키를 도출하는 키 합의 알고리즘.
- **Discrete Logarithm Problem (이산대수 문제, DLP)**: $Y = g^X \bmod p$에서 $p, g, Y$가 주어졌을 때 지수 $X$를 역산하는 것이 수학적으로 불가능한 난제.

</details>

- 정의/개념: 비밀키를 직접 전송하지 않고 공개값을 교환하여 **이산대수 난제를 통해 동일한 공유 비밀($g^{ab} \bmod p$)을 양단에서 독립 도출하는 키 합의 기술**
- 배경/필요성: 공용 네트워크 상에서 대칭키를 직접 전송할 수 없는 **키 배송 딜레마 및 도청자가 상존하는 채널에서의 안전한 비밀키 수립 불가**

#### 한줄 요약
- 이산대수 난제와 공개값 교환을 통해 비밀키 전송 없이 안전한 대칭 세션키를 양단에서 합의한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ECDHE (Elliptic Curve DHE)**: 유한체 지수 연산 대신 타원곡선 스칼라 곱셈($Q = d \cdot G$)을 사용하여 256비트 키로 초고속 키 합의를 수행하는 현대 표준.
- **MITM Vulnerability (중간자 취약점)**: DH 자체에는 인증(Authentication) 메커니즘이 없어 단독 사용 시 중간자 공격에 노출되므로 전자서명 결합이 필수적인 특성.

</details>

- **키 직접 전송 없는 안전한 합의**: 평문 비밀키를 네트워크에 노출하지 않고 **수학적 계산만으로 양단에서 동일한 마스터 비밀값 도출**
- **임시 키(Ephemeral) 기반 완벽한 PFS**: 매 세션마다 1회용 난수를 생성하여 **장기 개인키가 유출되어도 과거 도청 트래픽 복호화 불가**
- **타원곡선(ECDHE) 초고속 연산 최적화**: Curve25519 등을 활용하여 **256비트 짧은 키 길이로 RSA 3072비트 급의 보안 강도 제공**

#### 한줄 요약
- 키 직접 전송 배제, ECDHE 기반 순방향 비밀성(PFS), 타원곡선 초고속 최적화를 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **Domain Parameters ($p, g$)**: 유한체 모듈러 연산의 기준이 되는 2048비트 이상 안전한 소수($p$)와 원시근 생성원($g$).

</details>

```text
[디피-헬만 상호 키 합의 및 서명 연동 토폴로지]
|-- Alice (Client: 임시 개인값 a 무작위 생성 -> 공개값 A = g^a mod p 산출 및 서명)
`-- Public Insecure Network (도청자 Eve는 p, g, A, B만 관측 가능 -> 이산대수 난제로 a, b 계산 불가)
`-- Bob (Server: 임시 개인값 b 무작위 생성 -> 공개값 B = g^b mod p 산출 및 서명)
`-- Independent Key Calculation
    |-- Alice: K = B^a mod p = (g^b)^a = g^ab mod p
    `-- Bob:   K = A^b mod p = (g^a)^b = g^ab mod p
`-- Shared Master Secret Established (양단 간 동일한 256비트 대칭키 확립)
```

선의 의미: Alice와 Bob이 각각 임시 난수를 뽑아 공개값을 계산하고 전자서명을 첨부하여 상호 교환한 후 양단에서 동일한 $g^{ab} \bmod p$를 도출하는 구조

| 구성요소 | 핵심 엔지니어링 책임 | 주요 특징 |
|:---|:---|:---|
| **도메인 매개변수 ($p, g$)**| 유한체 모듈러 연산의 기준이 되는 **안전한 소수($p \ge 2048\text{bit}$) 및 생성원** | RFC 7919 FFDHE |
| **임시 개인값 ($a, b$)** | 각 당사자가 CSPRNG로 추출하여 **외부에 비공개 보관하는 1회용 난수** | Ephemeral Key |
| **공개값 ($A, B$)** | $g^a \bmod p$, $g^b \bmod p$로 계산되어 **네트워크를 통해 전송되는 공개 좌표** | Public Exchange |
| **전자서명 엔진** | 공개값 위조 및 중간자 공격을 차단하기 위해 **X.509 개인키로 전자서명 부착** | ECDSA / RSA-PSS |
| **HKDF 키 유도 모듈** | 도출된 공유 비밀($g^{ab}$)로부터 **대칭 암호화에 사용할 256비트 AES 키 추출**| RFC 5869 HKDF |

#### 한줄 요약
- 도메인 매개변수($p, g$), 임시 개인값($a, b$), 교환 공개값($A, B$), 전자서명 엔진, HKDF 모듈이 결합된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Curve25519 (X25519, RFC 7748)**: 몽고메리 곡선 상에서 타이밍 부채널 공격에 면역이며 극도로 빠른 스칼라 곱셈 연산을 제공하는 표준 타원곡선.

</details>

```text
ECDHE 타원곡선 파라미터 합의, 좌표 연산 및 공유 비밀 도출 파이프라인
        │
   1. [곡선 파라미터 합의] 통신 당사자(Alice, Bob)가 표준 타원곡선(Curve25519/P-256) 합의
        │
   2. [임시 개인값 생성] Alice와 Bob이 각각 256비트 암호학적 임시 개인값($d_A, d_B$)을 무작위 생성
        │
   3. [공개 좌표 산출] 타원곡선 기준점 $G$에 스칼라 곱을 수행하여 공개 좌표 $Q_A = d_A \cdot G$, $Q_B = d_B \cdot G$ 계산
        │
   4. [상호 전자서명 교환] X.509 인증서 개인키로 서명한 후 공개키 좌표($Q_A, Q_B$) 상호 전송
        │
   ▼
5. [공통 세션키 완성] 수신된 공개 좌표에 자신의 개인값을 곱셈($K = d_A Q_B = d_B Q_A = d_A d_B G$)하여 동일 세션키 완성
```

#### 한줄 요약
- 곡선 파라미터 합의 → 임시 개인값 생성 → 공개 좌표 산출 및 서명 교환 → 스칼라 곱셈 → 공통 세션키 수렴 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Static DH** vs **DHE (유한체)** vs **ECDHE (타원곡선)**.

</details>

| 비교 항목 | 정적 DH (Static DH) | 임시 유한체 DH (DHE / FFDHE) | 타원곡선 임시 DH (ECDHE) |
|:---|:---|:---|:---|
| **수학적 기반** | 유한체 이산대수 ($g^a \bmod p$) | 유한체 이산대수 ($g^a \bmod p$) | **타원곡선 이산대수 ($d \cdot G$)** |
| **개인값 수명주기** | **고정 개인값 장기 재사용** | **세션마다 1회용 임시 생성 및 파기** | **세션마다 1회용 임시 생성 및 파기** |
| **순방향 비밀성 (PFS)**| **미지원 (서버 키 유출 시 전면 해독)**| **완벽 지원 (과거 데이터 안전)** | **완벽 지원 (과거 데이터 안전)** |
| **연산 속도 및 부하** | 중간 | **매우 느림 (2048bit+ 대용량 소수 연산)**| **극도로 빠름 (256bit 고효율 곡선 연산)**|
| **표준 권고 상태** | 폐기 권고 | 제한적 사용 (RFC 7919 그룹) | **글로벌 표준 (TLS 1.3 필수 암호 스위트)**|

#### 한줄 요약
- 정적 DH는 PFS 미지원으로 폐기되었으며, DHE는 연산이 무겁고, ECDHE(X25519)가 현대 초고속 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Logjam Attack**: 1024비트 이하의 취약한 공용 소수 매개변수를 사용하는 DH 서버에 대해 사전 연산 테이블로 실시간 이산대수를 해독하는 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| DH 공개값 교환 시 인증 부재로 인한 **중간자 가로채기(MITM) 및 도청 사고** | **`X.509 PKI 인증서 기반 상호 서명(TLS 1.3 ECDHE-ECDSA/RSA)`** 강제 | 공개값 위변조 탐지 및 비인가 중간자 개입 100% 원천 차단 |
| 취약한 1024비트 정적 소수 매개변수 사용으로 인한 **Logjam 공격 노출** | **`최소 2048비트 이상의 RFC 7919 FFDHE 안전 소수군 강제 또는 X25519 전환`** | 소분군 공격 차단 및 이산대수 해독 계산 복잡도 $2^{128}$ 보증 |
| 비표준 커스텀 타원곡선 사용 시 공격자의 **악의적 매개변수 주입(Invalid Curve)** | **`NIST P-256 및 RFC 7748 Curve25519(X25519) 검증 표준 곡선만 허용`** | 곡선 파라미터 변조 공격 차단 및 상호운용성 완벽 확보 |
| 양자컴퓨터 출현 시 이산대수 난제 무력화 위협(SNDL) | **`고전 ECDHE와 양자내성 ML-KEM을 결합한 하이브리드 키 교환`** 적용 | 양자 컴퓨팅 시대에도 세션키 기밀성 영구 보장 |

#### 한줄 요약
- PKI 서명으로 MITM을 방어하고, RFC 7919/X25519로 Logjam을 차단하며, 표준 곡선으로 파라미터 변조를 방지한다.

## Ⅶ. 결론

- 공개 네트워크 상에서 대칭 세션키를 안전하게 수립하기 위한 **디피-헬만(Diffie-Hellman) 키 교환 아키텍처는 인터넷 보안 통신의 핵심 표준**이며, 실무 구현 시 **ECDHE 기반 순방향 비밀성(PFS) 의무화, X.509 PKI 전자서명과의 결합을 통한 MITM 방어, 미래 양자 컴퓨팅에 대응하는 ML-KEM 하이브리드 키 교환 전환**을 통합 구현하여 완결성 높은 안전한 키 합의 환경 완성

#### 한줄 요약
- 디피-헬만 키 교환은 ECDHE와 PKI 전자서명 및 PQC 하이브리드를 결합하여 순방향 비밀성이 보장된 안전한 키 합의를 실현하는 암호 기술이다.
