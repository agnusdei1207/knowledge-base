## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **ZTA(Zero Trust Architecture)** 는 네트워크 위치를 신뢰 근거로 삼지 않고 자원별 접근을 검증하는 아키텍처다.
- **묵시적 신뢰** 는 내부 위치나 기존 세션만으로 후속 접근을 자동 허용하는 신뢰 방식이다.
- **측면 이동** 은 침해한 주체가 내부의 다른 자원으로 공격 범위를 넓히는 행위다.

</details>

- 정의/개념: **제로 트러스트** 는 네트워크 위치를 신뢰 근거로 삼지 않고 주체•단말•맥락을 자원별로 지속 검증하여 최소 권한을 집행하는 보안 아키텍처
- 배경/필요성: 내부망 신뢰의 **권한 확장•측면 이동**

#### 한줄 요약

- 회사 안에서 접속했다는 이유로 모든 문을 열지 않고 매 자원 요청마다 사용자•기기•위험을 다시 확인한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **명시적 검증** 은 네트워크 위치와 무관하게 매 접근의 신원•기기•문맥을 확인하는 원칙이다.
- **최소 권한** 은 업무에 필요한 자원•행위•시간 범위만 허용하는 원칙이다.
- **지속 평가**: 세션 중에도 기기 상태와 위협 변화를 반영해 접근을 다시 판단하는 활동이다.

</details>

- **명시적 검증**: 네트워크 위치와 무관한 접근 판단
- **최소 권한**: 자원•행위•시간 범위로 권한 제한
- **지속 평가**: 세션 중 위험 변화의 재판단

#### 한줄 요약

- 한 번 로그인했어도 기기가 감염되거나 위치와 행동이 달라지면 이미 열린 접근을 줄이거나 끊는다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **PE(Policy Engine)** 는 신호와 정책을 평가해 접근 허용•거부를 결정하는 정책 엔진이다.
- **PA(Policy Administrator)** 는 결정에 따라 세션과 자격 증명을 생성•종료하는 정책 관리자다.
- **PEP(Policy Enforcement Point)** 는 주체와 보호 자원 사이에서 접근 결정을 집행하는 지점이다.
- **보호 자원** 은 접근 정책으로 보호하는 데이터•앱•서비스다.

</details>

```mermaid
block-beta
  columns 3
  A["주체•기기"]
  B["정책 집행점"]
  C["보호 자원"]
  D["정책 관리자"]
  E["정책 엔진•위험 신호"]
  A --- B --- C
  E --- D --- B
```

| 구성요소 | 책임 |
|:---|:---|
| **주체•기기** | 신원과 **단말 상태 제공** |
| **정책 집행점** | 접근의 **연결•감시•차단** |
| **보호 자원** | 데이터•앱•서비스의 **접근 경계** |
| **정책 관리자** | 세션과 **자격 증명 제어** |
| **정책 엔진•위험 신호** | 정책•민감도•위험의 **결정 근거** |

#### 한줄 요약

- 정책 엔진이 여러 신호를 보고 결정하면 관리자가 세션을 만들고 집행점이 자원 앞에서 그 결정을 계속 적용한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **신뢰 알고리즘**: 신원•기기•자원•행위•위협 신호를 결합해 접근 위험과 허용 범위를 계산하는 판단 로직이다.
- **재인증**: 세션 위험이 변했을 때 신원과 인증 요소를 다시 확인하는 절차이다.

</details>

```mermaid
sequenceDiagram
    participant U as 주체•기기
    participant E as 정책 집행점
    participant P as 정책 엔진
    participant A as 정책 관리자
    participant R as 보호 자원
    U->>E: 자원 접근 요청
    E->>E: 1. 접근 맥락•기기 상태 추출
    E->>P: 정책 결정 요청
    P->>P: 2. 신뢰 알고리즘•정책 평가
    P-->>A: 허용•거부•재인증 결정
    A->>A: 3. 범위•시간 제한 세션 생성
    A-->>E: 세션•집행 정책
    E->>E: 4. 최소 권한 정책 집행
    E->>R: 허용 요청
    R-->>E: 자원 응답
    loop 세션 유지 중
        E->>E: 5. 세션 위험 신호 수집
        E->>P: 변화 신호
        P-->>E: 제한•종료 결정
    end
    E-->>U: 접근 결과
```

**동작 원리**

- **1. 접근 맥락•기기 상태 추출**: 주체•자원•행위•위험 정보 구성
- **2. 신뢰 알고리즘•정책 평가**: 허용•거부•재인증과 최소 권한 산출
- **3. 범위•시간 제한 세션 생성**: 자격•행위•만료 조건 적용
- **4. 최소 권한 정책 집행**: 허용된 자원•행위 요청만 중계
- **5. 세션 위험 신호 수집**: 변화 시 제한•종료 판단 근거 갱신
#### 한줄 요약

- 접근 전에는 필요한 만큼만 열고 접근 중에는 위험 변화를 계속 보다가 조건이 달라지면 다시 인증시키거나 연결을 닫는다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **경계 중심 보안** 은 네트워크 경계 내부의 위치를 넓게 신뢰하는 보안 모델이다.
- **혼합 전환** 은 기존 경계를 유지하면서 중요 자원부터 ZTA로 바꾸는 방식이다.

</details>

| 보안 접근 모델 | 제로 트러스트 | 경계 중심 | 혼합 전환 |
|:---|:---|:---|:---|
| 적용 기준 | **분산 자원•원격 업무** | 단순 **폐쇄형 내부망** | 기존 환경의 **단계적 전환** |
| 핵심 특징 | **자원별 동적 접근 판단** | **내부 위치의 넓은 신뢰** | 중요 자원부터 검증 전환 |
| 한계 | **신호 품질•집행 가용성** | **내부 확산•VPN 과신** | **이중 정책•우회 경로** |

#### 한줄 요약

- 경계형은 내부에 들어오면 넓게 믿고 제로 트러스트는 자원마다 검증하며 혼합형은 중요한 자원부터 그 방식으로 바꾼다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **NIST(National Institute of Standards and Technology)** 는 미국의 기술 표준과 지침을 개발하는 기관이다.
- **SP(Special Publication) 800-207** 은 ZTA의 논리 구성요소•배치 모델•신뢰 알고리즘을 정의한다.
- **CISA(Cybersecurity and Infrastructure Security Agency)** 는 미국의 사이버 보안•기반시설 보호 기관이다.
- **ZTMM(Zero Trust Maturity Model) 2.0** 은 도메인별 ZTA 전환 성숙도를 제시한다.
- **제한 업무 모드** 는 신호 장애 때 필수 기능만 제한적으로 허용하는 운영 방식이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **논리 구조•신뢰 판단 편차** | **NIST SP 800-207 적용** | PE•PA•PEP의 **책임 정렬** |
| **단계적 전환•측정 부재** | **CISA ZTMM 2.0 활용** | 도메인별 **목표•격차 관리** |
| **신호 장애•집행 중단** | **제한 모드•고가용성 설계** | 오허용을 억제하며 **필수 업무 유지** |

#### 한줄 요약

- 중요 업무 앱은 접속 위치와 관계없이 사용자 신원•기기 관리 상태•세션 위험을 확인하고, 조건이 바뀌면 재인증하거나 세션을 차단한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **자원별 지속 검증**: 접근 시점뿐 아니라 열린 세션에서도 위험 변화를 관찰해 최소 권한을 유지하는 제로 트러스트 운영 원칙이다.
</details>

- 분산•원격은 **ZTA**, 단순 폐쇄망은 **경계형**, 기존 환경은 **혼합 전환**

#### 한줄 요약

- 제로 트러스트는 특정 제품이 아니라 모든 자원 요청을 최소 권한으로 판단하고 변화한 위험을 열린 세션에도 반영하는 운영 방식이다.
