## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **제로 트러스트 아키텍처(Zero Trust Architecture, ZTA)**: 내부 네트워크 위치를 신뢰하지 않고 모든 접근 요청의 신원, 기기, 맥락을 지속 검증하여 최소 권한을 집행하는 보안 아키텍처이다.
- **묵시적 신뢰(Implicit Trust)**: 네트워크 경계 내부 위치나 기본 세션만으로 추가 검증 없이 후속 접근을 자동 허용하는 보안 결함 방식이다.
- **측면 이동(Lateral Movement)**: 침투에 성공한 공격자가 내부 네트워크 내에서 인접 자원으로 접근 권한을 확산하는 공격 행위이다.

</details>

- 정의/개념: 모든 자원 접근을 지속 검증하는 **ZTA**
- 배경/필요성: 경계 내부의 **묵시적 신뢰**는 측면 이동 허용

#### 한줄 요약

- 내부 네트워크 접속 여부와 상관없이 매 자원 접근마다 신원·기기·위험을 지속 동적 평가하여 동적 세션을 제어한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **명시적 검증(Explicit Verification)**: 네트워크 위치와 무관하게 사용자 신원, 기기 무결성, 위치, 접근 목적을 매번 엄격히 검증하는 원칙이다.
- **최소 권한(Least Privilege)**: 업무 수행에 반드시 필요한 최소 자원, 작업 행위, 제한 시간만 허용하여 권한 오남용을 방지하는 원칙이다.
- **지속 평가(Continuous Evaluation / Risk-based Assessment)**: 최초 인증 후에도 세션 유지 중에 기기 상태 및 위협 위험도의 변화를 실시간 감지·재평가하는 방식이다.

</details>

- **명시적 검증**을 통해 신원 및 기기 보안태세(Posture)를 기반으로 접근 여부를 판단한다.
- **최소 권한** 원칙으로 대상 자원, 인가 행위, 유효 시간을 엄격하게 세분화하여 할당한다.
- **지속 평가**를 수행하여 세션 진행 중 단말 감염이나 위협 감지 시 권한을 즉시 축소 또는 격리한다.

#### 한줄 요약

- 최초 인증 성공 후에도 기기 이상이나 이상 행동 감지 시 접속 세션을 즉시 제어 또는 차단한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 엔진(Policy Engine, PE)**: 신원, 기기 상태, 위협 인텔리전스 신호를 종합 평가하여 자원 접근 허용/거부 정책을 결정하는 주체이다.
- **정책 관리자(Policy Administrator, PA)**: PE의 결정에 따라 세션을 암호화 제어하고 주체와 자원 간 접속 자격 증명 및 데이터 경로를 제어하는 구성요소이다.
- **정책 집행점(Policy Enforcement Point, PEP)**: 주체와 보호 자원 접점에서 PA의 통제 명령을 받아 실제 데이터 흐름을 라우팅, 감시, 차단하는 게이트웨이이다.
- **보호 자원(Protected Resource)**: ZTA 정책으로 보호되는 내부 데이터, 애플리케이션, 서비스 및 자산이다.

</details>

```text
[주체·기기]---[정책 집행점(PEP)]---[보호 자원]
                     |
              [정책 관리자(PA)]---[정책 엔진(PE)·위험 신호]
```

선의 의미: 주체와 보호 자원 사이의 PEP를 PA가 실시간 통제하고, PA는 PE의 위험 평가 알고리즘을 기반으로 제어 명령을 내리는 논리적 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 주체·기기 | 주체 신원 정보 및 단말 보안 무결성 상태 신호 제공 |
| 정책 집행점 | **PEP**가 주체-자원 간 데이터 통로의 실시간 중계·감시·차단 집행 |
| 보호 자원 | **보호 자원**의 데이터·앱·서비스 경계 보호 및 접근 격리 |
| 정책 관리자 | **PA**가 PE 결정 수용 후 제어 신호 송신 및 암호화 세션 제어 |
| 정책 엔진·위험 신호 | **PE**가 신뢰 알고리즘으로 위험 수치 계산 및 동적 허용/거부 판단 |

#### 한줄 요약

- PE가 위협 신호를 평가해 정책 결정을 내리면 PA의 통제에 의해 PEP가 보호 자원 앞단에서 접근을 정밀 제어한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **신뢰 알고리즘(Trust Algorithm)**: 신원, 기기 무결성, 위치, 시간, 데이터 민감도 등 복합 신호를 평가하여 위험 점수를 도출하는 분석 로직이다.
- **재인증(Re-authentication)**: 위험 점수 상승 또는 세션 만료 시 신원 및 MFA 통제를 재수행하도록 요구하는 처리 과정이다.
- **접근 맥락•기기 상태 추출(Access Context & Device Posture Extraction)**: 요청 주체의 신원, 단말의 OS/백신 업데이트 상태, 접속 IP를 수집하는 단계이다.
- **신뢰 알고리즘•정책 평가(Trust Algorithm & Policy Evaluation)**: 수집된 신호와 정의된 규칙을 대조하여 허용 여부 및 추가 인증 필요성을 계산하는 단계이다.
- **범위•시간 제한 세션 생성(Scoped & Time-limited Session Generation)**: 허용된 자원에 한해 동작 유효시간이 포함된 암호화 세션 키를 구성하는 단계이다.
- **최소 권한 정책 집행(Least Privilege Policy Enforcement)**: PEP를 통해 승인된 패킷만 목적지 자원으로 포워딩하는 단계이다.
- **세션 위험 신호 수집(Session Risk Signal Collection)**: 세션 동작 중 발생되는 단말 이상 행위 및 네트워크 패킷 이상을 지속 모니터링하는 단계이다.

</details>

```text
[주체·기기]
      |
      `-- 자원 접근 요청
                |
                v
[정책 집행점(PEP)]
      |
      v
1. 접근 맥락·기기 상태 추출
      |
      v
[정책 엔진(PE)]
      |
      v
2. 신뢰 알고리즘·정책 평가
      |
      v
[정책 관리자(PA)]
      |
      v
3. 범위·시간 제한 세션 생성
      |
      v
[정책 집행점(PEP)]
      |
      v
4. 최소 권한 정책 집행
      |
      v
[보호 자원] -- 자원 응답
      |
      v
+----------------------------------+
| 세션 유지 중                     |
|                                  |
|  5. 세션 위험 신호 수집          |
|          |                       |
|          `-- 위험 변화           |
|                 |                |
|                 v                |
|       [PE 재평가·PEP 제한/종료]  |
+----------------------------------+
      |
      `-- 접근 결과 ----> [주체·기기]
```

### 동작 원리

1. 접근 맥락•기기 상태 추출: 신원•단말 무결성 수집
2. 신뢰 알고리즘•정책 평가: 허용•거부•재인증 결정
3. 범위•시간 제한 세션 생성: 제한된 암호화 자격 생성
4. 최소 권한 정책 집행: 승인 경로만 라우팅
5. 세션 위험 신호 수집: 위험 변화 시 재평가•종료

#### 한줄 요약

- 접근 요청 평가부터 세션 유지 중 지속적인 모니터링을 거쳐 위협 변동 시 즉시 세션 차단 또는 재인증을 집행한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **경계 중심 보안(Perimeter-based Security)**: 네트워크 외곽 방화벽/VPN 중심 통제로 내부 망 접속자에 대해 고정적 신뢰를 부여하는 보안 방식이다.
- **혼합 전환(Hybrid Transition)**: 기존 경계 보안을 유지하면서 핵심 자원부터 단계적으로 제로 트러스트 모델을 병행 도입하는 방식이다.

</details>

| 보안 접근 모델 | 제로 트러스트(ZTA) | 경계 중심 보안 | 혼합 전환 모델 |
|:---|:---|:---|:---|
| 적용 기준 | 분산 자원•멀티 클라우드•원격 근무 | 전통적 폐쇄형 사내 네트워크 | 기존 온프레미스 기반의 단계적 전환 |
| 핵심 특징 | **ZTA** 기반 동적 자원별 최소 권한 통제 | **경계 중심 보안**의 내부 네트워크 묵시적 신뢰 | **혼합 전환**을 통한 주요 자원 우선 검증 |
| 한계 | 신호 연동 복잡성 및 집행 성능 이슈 | 내부 확산(**측면 이동**) 및 탈취 계정 무방비 | 정책 이중화 및 관리 공백 우려 |

#### 한줄 요약

- 경계 중심 보안의 묵시적 신뢰 한계를 극복하기 위해 자원 단위의 동적 검증 체계인 제로 트러스트로 전환한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST SP 800-207**: 제로 트러스트 아키텍처의 표준 개념, 논리 구성요소, 배치 모델 및 신뢰 알고리즘을 규정한 핵심 표준이다.
- **CISA ZTMM 2.0 (Zero Trust Maturity Model 2.0)**: 신원, 기기, 네트워크, 애플리케이션, 데이터 등 5개 축별 ZTA 전환 성숙도 모델을 제시하는 미국 지침이다.
- **제한 업무 모드(Restricted Operational Mode / Fail-secure Mode)**: 신호 연동 오류 발생 시 전면 허용이 아닌 최소 업무만 보장하는 보안 모드이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 아키텍처 설계 및 표준 미비 | **NIST SP 800-207** 표준 적용 | PE•PA•PEP 구성요소 간 가시성 및 통제 체계 표준화 |
| 로드맵 부재 및 혼선 | **CISA ZTMM 2.0** 성숙도 모델 활용 | 5대 영역별 단계적 전환목표 설정 및 격차 해소 |
| 평가 엔진 장애 시 가용성 저하 | **제한 업무 모드** 설계 및 HA 구성 | Fail-Secure 원칙 준수하에 핵심 서비스 연속성 유지 |

#### 한줄 요약

- NIST 표준과 CISA 성숙도 모델에 기반하여 단계별 이행 계획을 수립하고 Fail-Secure 중심 장애 대책을 확보한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **자원별 지속 검증(Resource-level Continuous Verification)**: 접근 시점 단 1회의 인증에 그치지 않고 자원 사용 전 과정에서 세션 무결성을 모니터링하는 통제 원칙이다.

</details>

- **자원별 지속 검증** 원칙을 구현하기 위해 클라우드·원격 환경은 **ZTA**, 과도기적 구축 환경은 **혼합 전환** 체계를 도입한다.

#### 한줄 요약

- 분산 환경은 **ZTA**, 과도기 환경은 **혼합 전환** 적용
