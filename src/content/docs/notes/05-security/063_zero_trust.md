## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **제로 트러스트 아키텍처(ZTA: Zero Trust Architecture / NIST SP 800-207)**: "네트워크 내부(사내망)에 위치한 모든 자원과 사용자는 신뢰할 수 있다"는 전통적인 경계 기반 보안의 묵시적 신뢰(Implicit Trust)를 완전히 배제하고, "절대 신뢰하지 않고 항상 검증한다(Never Trust, Always Verify)"는 철학 하에 모든 접근 요청마다 신원, 단말 무결성, 환경 맥락을 지속 평가하여 동적으로 최소 권한을 부여하는 보안 아키텍처.
- **묵시적 신뢰 및 측면 이동(Implicit Trust & Lateral Movement Defect)**: 방화벽/VPN 경계를 통과하여 사내 IP 대역에 진입한 트래픽에 무제한적인 내부망 접근을 허용함으로써, 엔드포인트 단말 1대가 악성코드에 감염되었을 때 공격자가 내부망 전체로 확산(Lateral Movement)되는 치명적 보안 결함.

</details>

- 정의/개념: NIST SP 800-207 표준에 기반하여 제어 평면(Control Plane: PE 정책엔진 & PA 정책관리자)과 데이터 평면(Data Plane: PEP 정책집행점)을 물리적으로 분리하고, 명시적 검증(Verify Explicitly) $\rightarrow$ 최소 권한 부여(Least Privilege) $\rightarrow$ 침해 전제(Assume Breach) 의 3대 원칙을 전사 인프라에 구현하는 차세대 보안 패러다임
- 배경/필요성: 클라우드 컴퓨팅, 원격/재택근무 확산 및 SaaS 도입으로 인해 전통적인 물리적 네트워크 경계(Perimeter)가 완전히 붕괴되었으며, "내부망 IP는 신뢰할 수 있다"는 묵시적 신뢰(Implicit Trust) 모델로 인해 단말 1대 침해 시 내부망 전체로의 횡적 이동(Lateral Movement)을 방어하지 못하는 치명적 한계를 드러냄에 따라, "절대 신뢰하지 않고 항상 검증한다(Never Trust, Always Verify)"는 철학 하에 제어 평면(PE/PA)과 데이터 평면(PEP)을 물리적으로 분리하는 NIST SP 800-207 제로 트러스트 아키텍처(ZTA)를 도입하여 명시적 지속 검증(Verify Explicitly), 최소 권한 접근(Least Privilege), 침해 전제(Assume Breach) 3대 원칙 내재화 및 횡적 이동의 원천 차단을 달성할 필요

#### 한줄 요약
- 제로 트러스트는 신뢰를 없애는 것이 아니라 신뢰의 근거를 네트워크 위치에서 신원·단말 상태로 옮기고 그 유효 기간을 세션 단위로 줄인 선택이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **NIST SP 800-207 제로 트러스트 3대 핵심 원칙**:
  1. **명시적 검증 (Verify Explicitly)**: 사용 가능한 모든 데이터(신원, 위치, 기기 상태, 데이터 분류, 이상 징후)를 종합하여 항상 인증/인가.
  2. **최소 권한 사용 (Use Least Privileged Access)**: JIT/JEA, 위험 기반 적응형 정책, 데이터 보호를 통해 사용자 접근을 제한.
  3. **침해 전제 (Assume Breach)**: 공격자가 이미 네트워크 내부에 존재한다고 가정하고 마이크로 세그먼테이션과 엔드투엔드 암호화 집행.

</details>

- 지속적 런타임 신뢰 평가 (Continuous Adaptive Trust): 로그인 시점 1회 인증에 그치지 않고, 세션 유지 중 단말 위험도 변경 시 즉각 세션 차단
- 자원의 은닉화 (Dark IP / SPA): 승인되지 않은 사용자에게는 보호 대상 자원의 IP/포트를 인터넷 및 내부망에서 완전히 은닉
- 세분화된 마이크로 세그먼테이션: 네트워크를 워크로드 및 애플리케이션 단위의 격리된 세그먼트로 분할하여 횡적 이동 원천 차단

#### 한줄 요약
- 세 원칙은 모두 접근 1건마다 검증 연산과 텔레메트리 수집 비용을 상시 지불하는 대가로 침해가 번지는 폭발 반경을 줄인 결과다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **NIST SP 800-207 논리적 3대 컴포넌트**:
  - **PE (Policy Engine)**: 신뢰 알고리즘을 구동하여 자원 접근 허용/거부를 판정하는 두뇌.
  - **PA (Policy Administrator)**: PE의 결정을 수신하여 PEP에 통신 세션 수립/해제 명령을 하달하는 컨트롤러.
  - **PEP (Policy Enforcement Point)**: 주체와 자원 사이의 데이터 통신 경로를 물리적으로 개폐하는 게이트웨이/에이전트.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 제어 평면 (Control Plane: 신뢰 평가 및 정책 통제 계층) ]              │
│                                                                         │
│  ┌──────────────────────────┐             ┌──────────────────────────┐  │
│  │ [ 정책 엔진 (Policy Engine) ] ◀──────▶ │ [ 정책 관리자 (Policy Admin) ]│
│  │  ├─ 신뢰 알고리즘 계산   │ (결정 전달) │  ├─ 동적 세션 토큰 발행 │  │
│  │  └─ 이상 행위 위험도 평가 │             │  └─ PEP 통신 명령 하달   │  │
│  └──────────────▲───────────┘             └────────────┬─────────────┘  │
│                 │ (위협 텔레메트리 주입)                │                │
│  ┌──────────────┴───────────────────────────────────┐  │                │
│  │ [ CDM / IdP / EDR / SIEM / 위협 인텔리전스 (CTI) ]│  │                │
│  └──────────────────────────────────────────────────┘  │                │
└────────────────────────────────────────────────────────┼────────────────┘
                                                         │ (세션 수립 명령)
┌────────────────────────────────────────────────────────▼────────────────┐
│ [ 데이터 평면 (Data Plane: 실제 트래픽 전송 계층) ]                    │
│                                                                         │
│  [ 주체 / 엔드포인트 기기 ] ──(mTLS 통신)──▶ [ 정책 집행점 (PEP) ] ────▶ [ 보호 자원 (Resource) ] │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 제어 평면의 PE가 위협 신호를 종합하여 판정하면 PA가 세션 명령을 내리고, 데이터 평면의 PEP가 주체와 보호 자원 간의 트래픽을 집행하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **정책 엔진 (PE)** | 신원, 기기 무결성, CTI 신호를 바탕으로 신뢰 점수를 산출하고 접근 허용/거부 판정 | Control Plane |
| **정책 관리자 (PA)** | PE의 결정을 바탕으로 주체와 자원 간의 암호화 통신 채널 수립 및 세션 종료 명령 | Control Plane |
| **정책 집행점 (PEP)** | 데이터 경로에서 트래픽을 가로채어 PA의 명령에 따라 연결을 생성, 감시, 차단 | Data Plane |
| 신원 제공자 (IdP) | 사용자 및 서비스 계정의 다중 인증(MFA), FIDO2 피싱 저항성 자격증명 관리 | Trust Signal |
| 엔드포인트 보안 (EDR/MDM)| 단말기의 OS 패치 상태, 백신 가동, 탈옥 여부 등 기기 상태(Posture) 신호 제공 | Posture Source |

#### 한줄 요약
- 판정을 데이터 경로 밖 제어 평면으로 빼낸 덕에 자원 메타데이터는 은닉되지만, 그 대가로 PE의 판정 지연과 가용성이 모든 접근의 임계 경로에 놓인다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **지속적 적응형 신뢰 평가(Continuous Adaptive Trust Evaluation) 흐름**:
  1. 접근 요청 시 초기 인증/단말 검증
  2. 제어 평면의 동적 신뢰 점수 계산
  3. 데이터 평면의 암호화 세션 개설
  4. 세션 진행 중 실시간 위협 모니터링
  5. 이상 징후 발생 시 세션 즉시 파기

</details>

```text
1. [접근 요청] 엔드포인트 기기가 PEP로 사내 ERP 자원 접근 요청 ➔ PEP가 트래픽 인터셉트
            │
            ▼
2. [컨텍스트 텔레메트리 수집] PEP가 사용자 신원(IdP), 기기 상태(EDR), 위치/시간 정보를 수집하여 PE로 전송
            │
            ▼
3. [신뢰 알고리즘 및 정책 평가]
    ├─ PE가 보안 정책 및 CTI 위협 피드 대조: "정상 신원 + EDR 정상 + 평소 접속 국가" 확인
    └─ 접근 허용 결정(Decision)을 PA로 전달
            │
            ▼
4. [동적 세션 수립] PA가 PEP에 명령을 내려 주체와 보호 자원 간의 암호화된 mTLS 통신 터널 개설 (1시간 TTL)
            │
            ▼
5. [세션 중 지속적 위험 감시 (Continuous Monitoring)]
    ├─ 세션 도중 엔드포인트 단말에서 미인가 백도어 프로세스 실행 감지 (EDR 텔레메트리)
    └─ PE가 신뢰도를 즉시 위험(High Risk)으로 재평가 ➔ [PA가 PEP에 세션 즉시 강제 종료(Kill) 하달]
```

1. 상시 불신 원칙: 네트워크 위치와 무관하게 모든 요청을 신규 접근으로 간주하여 엄격 검증
2. 다차원 위험 점수화: 정적 규칙이 아닌 신원, 단말, 네트워크, 행위 맥락을 통합한 동적 점수 평가
3. 제어/데이터 평면 격리: 공격자가 데이터 평면을 스캔하더라도 제어 평면의 자원 메타데이터 은닉
4. 마이크로 터널링: 전사 네트워크 연결이 아닌 특정 단일 애플리케이션에 대한 1:1 전용 통신 채널만 개설
5. 실시간 위협 피드백: 세션 수립 후에도 위협 감지 즉시 연결을 능동적으로 차단하는 Closed-Loop 구현

#### 한줄 요약
- 세션 수립 시점의 판정만으로는 접속 이후에 감염된 단말을 걸러낼 수 없으므로, 신뢰 평가를 세션 수명 내내 되풀이하는 비용이 이 구조가 감수한 본질적 부담이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CISA ZTMM 2.0 (제로 트러스트 성숙도 모델) 5대 기둥**:
  1. 신원(Identity) 2. 기기(Device) 3. 네트워크(Network) 4. 애플리케이션(Workload) 5. 데이터(Data).

</details>

| 비교 항목 | 경계 중심 보안 (Perimeter Security) | 제로 트러스트 보안 (Zero Trust Architecture) |
|:---|:---|:---|
| 신뢰 모델 | 위치 기반 묵시적 신뢰 (사내망 IP = 신뢰) | 위치 불신, 명시적 지속 검증 (Never Trust) |
| 접근 통제 방식 | 방화벽 / IPsec VPN 기반 광범위 네트워크 접속 | ZTNA 기반 특정 애플리케이션 단위 세분화 접속 |
| 침해사고 파급력 | 경계 붕괴 시 내부망 전체 측면 이동(횡적 확산) | 마이크로 세그먼테이션으로 감염 단말 격리 |
| 주요 통제 요소 | IP 주소, 서브넷, 포트 번호 | 사용자 신원, 단말 무결성, 실시간 위험 맥락 |
| 가시성 및 감사 | 경계 방화벽 로그 위주 제한적 가시성 | 전 구간 엔드투엔드 암호화 및 전수 텔레메트리 분석 |

#### 한줄 요약
- 경계 보안은 IP 기반 묵시적 신뢰, 제로 트러스트는 신원/기기 기반 명시적 지속 검증이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **Fail-Secure vs Fail-Open**: 중앙 PE/PA 엔진 장애 발생 시 보안을 위해 모든 접근을 기본 차단(Fail-Secure)할 것인지, 비즈니스 연속성을 위해 제한된 생존 통신을 허용(Fail-Open)할 것인지에 대한 아키텍처 의사결정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 벤더사마다 ZTA 개념이 상이하여 이종 보안 솔루션 간 신호 연동이 불가능하고 단편화된 사일로(Silo) 발생 | **NIST SP 800-207** 표준 논리 아키텍처(PE-PA-PEP) 기반 개방형 표준 API(OpenAPI/OIDC) 연동 체계 강제 | 솔루션 간 위협 텔레메트리 연동 100% 달성 및 특정 벤더 종속성 탈피 |
| 기존 레거시 인프라를 일괄 빅뱅(Big-Bang) 방식으로 전환하려다 서비스 연결 단절 및 대규모 업무 마비 장애 | CISA ZTMM 2.0 5대 기둥(신원/기기/네트워크 등) 기반의 단계적 하이브리드 전환 로드맵 수립 | 비즈니스 연속성 무중단 유지 및 조직 내 안정적 제로 트러스트 안착 |
| 중앙 정책 엔진(PE) 서버 장애 발생 시 전사 인증이 전면 거부되어 핵심 업무가 마비되는 단일 장애점(SPOF) | PE/PA 제어 평면의 다중 리전 분산 고가용성(HA/DR) 구축 및 비상 시 제한적 캐시 기반 **Fail-Secure** 모드 운영 | 중앙 엔진 다운 시에도 미션 크리티컬 서비스 생존성 99.999% 확보 |

#### 한줄 요약
- 판정 권한을 중앙 PE로 모으면 가용성 위험도 함께 모이므로, 표준 연동이나 단계적 전환보다 Fail-Secure 정책과 제어 평면 다중화가 도입의 실질적 전제가 된다.

## Ⅶ. 결론

- 물리적 네트워크 경계에 의존하던 30년 전통의 경계 보안 패러다임을 근본적으로 대체하고 디지털 전환 시대의 전사 사이버 보안을 지탱하는 현대 엔터프라이즈 및 클라우드 보안(NIST SP 800-207 / CISA ZTMM 2.0)의 최상위 표준 보안 철학이자 청사진으로 확고히 자리 잡았으며, AI 기반 동적 위험 분석 및 SASE/ZTNA 통합 프레임워크로 전면 진화하는 가운데, 실무 엔터프라이즈 제로 트러스트 전환 시에는 CISA ZTMM 2.0 5대 기둥(신원·기기·네트워크·애플리케이션·데이터)에 기반한 단계적 성숙도 전환 로드맵 수립, 신원(IdP)과 단말 상태(EDR)를 결합한 지속적 적응형 신뢰 평가(Continuous Adaptive Trust) 엔진 운영, ZTNA 및 마이크로 세그먼테이션을 통한 내부 횡적 이동 원천 차단, 제어 평면(PE/PA) 분산 HA 구성을 통한 비즈니스 가용성 99.999% 보장을 결합하여 완벽한 제로 트러스트 엔터프라이즈 보안 생태계를 완성

#### 한줄 요약
- 제로 트러스트는 한 번에 도입하는 제품이 아니라 자원 위험도에 비례해 검증 비용을 더 치를 구간을 골라내는 우선순위 판단이다.
