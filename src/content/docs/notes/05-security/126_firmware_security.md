## 미리 알고가기

- **펌웨어 (Firmware)**: 하드웨어를 초기화·제어하는 저수준 소프트웨어
- **하드코딩 자격증명 (Hard-coded Credentials)**: 계정·암호·키를 고정해 추출·공유되는 결함
- **신뢰 루트 (Root of Trust, RoT)**: 신뢰 사슬을 시작하는 최소 보호 기반
- **보안 부팅 (Secure Boot)**: 서명과 정책으로 부팅 구성요소를 검증함
- **인증 업데이트 (Authenticated Update)**: 서명된 정식 펌웨어만 설치함
- **롤백 방지 (Anti-rollback)**: 구형 정식 버전으로의 되돌림 공격을 차단함
- **SBOM (Software Bill of Materials)**: 펌웨어에 포함된 소프트웨어 구성요소와 버전을 기록한 명세서
- **이중 이미지**: 업데이트 실패 시 이전의 정상 펌웨어로 복구하도록 두 이미지 영역을 유지하는 방식
- **복구 파티션**: 정상 부팅 실패 때 복구용 펌웨어를 실행하도록 분리한 저장 영역
- **RoT·SBOM 읽기**: “알오티·에스봄”으로 읽으며 신뢰 루트와 소프트웨어 구성 명세의 영문 머리글자임



## Ⅰ. 개요

- 정의/개념: 펌웨어의 부팅·비밀·업데이트·복구 신뢰 사슬을 보호
- **배경/필요성**: 운영체제 보안만으로 하위 펌웨어 변조와 지속성 제거 곤란

### 쉽게 이해하기 (학습용)

- 운영체제가 집이라면 펌웨어는 기초에 해당하므로 기초가 바뀌면 위의 보안 기능도 믿기 어려움

## Ⅱ. 특징

- 초기 실행으로 침해 시 탐지·복구가 어렵다.
- 공용 비밀 사용 시 한 번의 추출로 전체 영향을 준다.
- 인증 업데이트·롤백 방지·복구로 악성 코드 주입을 통제한다.

### 쉽게 이해하기 (학습용)

- 업데이트를 막으면 취약점을 못 고치고 아무 업데이트나 허용하면 공격자가 펌웨어를 바꿀 수 있음

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 신뢰 루트 | 검증 키·정책의 변조 방지 보호 |
| 부트 검증 | 이미지 서명·버전의 연속 검증 |
| 비밀 관리 | 장치 키의 생성·주입·폐기 통제 |
| 업데이트 | 인증 설치·롤백 방지 제공 |

```text
[제조 영역] ----> [서명된 이미지]
      |                 |
      v                 v
[장치 내부] ---> [RoT 검증] ---> [업데이트]
      |                 |
[비밀·키 저장] <--- [운영 상태]
```

### 쉽게 이해하기 (학습용)

- 첫 코드가 다음 코드를 검증하고 실패하면 신뢰 상태로 복구함

## Ⅳ. 원리 및 절차 흐름도

```text
분석
 ↓
구현
 ↓
통제
 ↓
배포
 ↓
복구
```

| 절차 | 설명 |
|:---|:---|
| 분석 | 물리·공급망·갱신 위험을 분석함 |
| 구현 | 부트·메모리·격리를 구현함 |
| 통제 | 서명키·빌드 환경·SBOM을 보호함 |
| 배포 | 검증 후 단계 배포를 수행함 |
| 복구 | 취약 버전을 식별하고 복구함 |

### 쉽게 이해하기 (학습용)

- 펌웨어 파일만 검사하지 말고 서명키와 빌드 서버, 배포·복구 경로까지 함께 보호해야 함

## Ⅴ. 펌웨어 비밀 관리 방식 비교

| 비교 축 | 공용 비밀 | 장치별 비밀 | 고유값 파생 |
|:---|:---|:---|:---|
| 적용 기준 | 사용 금지하고 제거할 대상 | 장치별 회수·교체 추적이 필요할 때 | 원시 키 저장을 줄이고 싶을 때 |
| 핵심 특징 | 같은 비밀을 코드에 고정 | 제조 때 장치별 비밀 주입 | 장치 고유값에서 비밀 파생 |
| 한계 | 한 번 추출되면 장치군 전체 침해 | 제조 등록부·주입 공정 노출 | 파생 함수·고유값 노출로 재생성 |

> 요약: 신뢰 루트 기반 비밀 관리와 단계별 보안 통제 필요

### 쉽게 이해하기 (학습용)

- 공용 비밀보다 장치별 비밀과 안전한 파생 방식이 확산 위험을 줄임

## Ⅵ. 실무 사례

1. OTA 펌웨어의 **서명·버전 검증과 안전한 롤백**

### 쉽게 이해하기 (학습용)

- 장치는 제조사가 서명한 펌웨어와 허용 버전을 확인한 뒤 업데이트하고 실패 시에도 취약 버전이 아닌 서명된 복구 이미지로 전환한다.

## Ⅶ. 결론

- 펌웨어 변조와 취약 버전 재설치를 막기 위해 신뢰 루트·서명키·버전·장치별 비밀·복구 경로를 검토하여, 인증된 변경과 안전한 복구를 보장해야 한다.

### 쉽게 이해하기 (학습용)

- 안전한 펌웨어는 변조를 막는 것뿐 아니라 변조를 알아내고 정상 상태로 되돌릴 수 있어야 함
