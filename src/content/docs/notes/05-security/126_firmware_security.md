## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **펌웨어 보안(Firmware Security)**: 하드웨어를 초기화•제어하는 저수준 소프트웨어의 실행 무결성, 자격증명 보호와 서명 기반 갱신 신뢰성을 보장하는 활동이다.

</details>

- 정의/개념: 하드웨어와 운영체제 사이의 실행•갱신 신뢰성을 보장하는 **펌웨어 보안**이다.
- 배경/필요성: 운영체제 보안만으로는 하위 펌웨어의 지속성 공격을 차단할 수 없다.

#### 한줄 요약

- 정의/개념: 하드웨어 부팅 초기 단계에 실행되는 펌웨어 변조 시 상위 운영체제 보안 체계 전체의 신뢰성이 와해되는 펌웨어 보안 영역이다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **하드코딩 자격증명**: 계정•암호•키를 코드에 고정해 추출•공유될 수 있는 결함이다.
- **인증 업데이트**: 승인된 주체가 서명한 정식 펌웨어만 설치하는 기능이다.

</details>

- 최초 실행•고권한 특성으로 탐지•복구가 어렵다.
- **하드코딩 자격증명**은 동일 장치군으로 피해를 확산시킨다.
- **인증 업데이트**로 서명•버전•복구를 검증한다.

#### 한줄 요약

- 업데이트를 막으면 취약점을 못 고치고 아무 업데이트나 허용하면 공격자가 펌웨어를 바꿈이 핵심이다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **신뢰 루트**: 신뢰 사슬을 시작하는 변조 방지 하드웨어•코드•키 기반이다.
- **롤백 방지**: 취약한 구형 정식 버전의 재설치를 차단하는 기능이다.

</details>

```text
펌웨어 신뢰 구조
├─ 하드웨어 신뢰 루트
├─ 부팅 진위•무결성 검증
├─ 장치별 비밀•서명키
├─ 인증 갱신•롤백 방지
└─ 변조 탐지•안전 복구
```

| 구성요소 | 책임 |
|:---|:---|
| 하드웨어 신뢰 루트 | **신뢰 루트**의 검증 키•정책 보호 |
| 부팅 진위•무결성 검증 | 단계별 서명•버전 확인 |
| 장치별 비밀•서명키 | 생성•주입•회전•폐기 통제 |
| 인증 갱신•롤백 방지 | **롤백 방지**와 대상•서명 검증 |
| 변조 탐지•안전 복구 | 정상 이미지 전환•증적 확보 |

#### 한줄 요약

- 바꿀 수 없는 첫 코드가 다음 코드를 검증하고 실패하면 알려진 정상 이미지로 복구하는 것이 핵심이다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **OTA(Over-the-Air Update)**: 펌웨어를 무선 통신으로 원격 배포하는 방식이다.
- **SBOM(Software Bill of Materials)**: 구성요소•버전•의존성을 기록한 소프트웨어 자재명세서이다.
- **펌웨어 이미지•매니페스트 서명**: 이미지의 대상•버전•구성정보에 제조사 서명을 생성하는 단계이다.
- **대상•버전•해시•서명 검증**: 장치 정책과 배포물의 진위•무결성•버전을 확인하는 단계이다.
- **설치•부팅•복구 판정**: 원자적 설치와 신규 버전 확정 또는 복구 전환을 결정하는 단계이다.

</details>

```text
펌웨어 이미지•매니페스트
   │
   ▼
1. 펌웨어 이미지•매니페스트 서명
   │
   ▼
2. 대상•버전•해시•서명 검증
   ├─ 검증 실패 ──► 설치 거부
   └─ 검증 성공
          │
          ▼
3. 설치•부팅•복구 판정
   ├─ 부팅 성공 ──► 신규 버전 확정
   └─ 부팅 실패 ──► 서명된 복구 이미지 전환
```

### 동작 원리

- **1. 펌웨어 이미지•매니페스트 서명**: **펌웨어 이미지•매니페스트 서명**에서 **SBOM**•대상•버전•정책을 결합한다.
- **2. 대상•버전•해시•서명 검증**: **대상•버전•해시•서명 검증**으로 장치 정책과 배포물의 일치를 확인한다.
- **3. 설치•부팅•복구 판정**: **설치•부팅•복구 판정**으로 원자적 설치와 부팅 허용 여부를 결정한다.

- 원격 배포에는 **OTA**를 사용하되 같은 서명•버전•복구 정책을 적용한다.

#### 한줄 요약

- 파일 서명뿐 아니라 어떤 장치에 어떤 순서로 설치할지와 실패 후 복구까지 검증하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **장치별 비밀**: 하나의 장치가 노출돼도 동일 모델 전체로 피해가 확산되지 않게 개별 관리하는 비밀이다.

</details>

| 펌웨어 비밀 관리 | 공용 비밀 | 장치별 비밀 | 고유값 파생 |
|:---|:---|:---|:---|
| 적용 기준 | 사용 금지•제거 대상 | 장치별 회수•교체 필요 | 원시 키 저장 최소화 |
| 핵심 특징 | **하드코딩 자격증명** 사용 | **장치별 비밀** 주입 | 장치 고유값으로 파생 |
| 한계 | 한 번 추출로 전체 침해 | 제조 등록부•주입 노출 | 파생 함수•고유값 노출 |

> 요약: 공용 비밀을 없애고 장치별 수명주기를 추적하는 것이 핵심이다.

#### 한줄 요약

- 장치 하나의 비밀이 노출돼도 같은 모델 전체가 침해되지 않도록 비밀을 분리하는 것이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **SP(Special Publication)**: NIST가 발행하는 특별간행물이다.
- **NIST SP 800-193**: 플랫폼 펌웨어의 보호•탐지•복구 지침이다.
- **IETF(Internet Engineering Task Force)**: 인터넷 표준을 개발하는 국제 기술기구이다.
- **RFC(Request for Comments)**: IETF의 인터넷 표준 문서 유형이다.
- **IoT(Internet of Things)**: 사물과 네트워크를 연결한 사물인터넷이다.
- **IETF RFC 9019**: IoT 펌웨어 업데이트 구조를 정의한 표준이다.
- **IETF RFC 9124**: 펌웨어 매니페스트 정보 모델을 정의한 표준이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 변조 탐지 후 정상 상태로 복구할 경로 부재 | **NIST**의 **SP**, **NIST SP 800-193** 적용 | 보호•탐지•복구 확보 |
| **IoT** 갱신 참여자별 신뢰 책임이 불명확 | **IETF**의 **RFC**, **IETF RFC 9019** 적용 | 참여자•신뢰 경계 명확화 |
| 배포물의 대상•버전•서명을 판별할 정보 부족 | **IETF RFC 9124** 적용 | 대상•버전•서명 검증 |

#### 한줄 요약

- 제조사가 서명한 매니페스트의 장치 대상과 버전을 검증하고 실패 시에도 취약본이 아닌 서명된 복구 이미지로 전환한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **안전 복구**: 변조•설치 실패를 탐지하고 서명된 정상 이미지로 되돌리는 기능이다.

</details>

- **안전 복구**가 가능한 경우에만 서명•대상•버전을 검증한 펌웨어를 설치한다.

#### 한줄 요약

- 변조 차단뿐 아니라 변조를 알아내고 정상 상태로 안전하게 되돌릴 수 있어야 한다.
