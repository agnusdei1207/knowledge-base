## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 설계 원칙**: 시스템 구조와 기본 동작에 보안을 내재화해 예외•우회 경로를 줄이는 기준이다.

</details>

- 정의/개념: 기본 거부•최소 권한•완전 중재•안전 실패를 구조와 기본 동작에 내재화하는 **보안 설계 원칙**이다.
- 배경/필요성: 사후 통제만으로는 예외•공유 권한•우회 경로를 제거할 수 없다.

#### 한줄 요약

- 구현 후 보안 통제를 추가하기보다 설계 단계에서 공격 표면과 권한 범위를 최소화하는 접근이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **안전한 기본값**: 허용 근거가 없으면 접근을 거부하는 원칙이다.
- **최소 권한**: 필요한 권한만 필요한 시간 동안 부여하는 원칙이다.
- **완전 중재**: 모든 자원 접근을 현재 정책과 권한으로 매번 검사하는 원칙이다.

</details>

- **안전한 기본값**으로 허용 근거 없는 접근을 거부한다.
- **최소 권한**으로 침해 범위를 제한한다.
- **완전 중재**로 현재 정책을 계속 집행한다.

#### 한줄 요약

- 매 요청의 대상·행위·**현재 권한 재검사**

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **메커니즘 경제성**: 보안 구조를 작고 단순하게 만드는 원칙이다.
- **공개 설계**: 알고리즘 은닉보다 제한된 비밀에 의존하는 원칙이다.
- **권한 분리**: 중요 작업에 둘 이상의 독립 조건을 요구하는 원칙이다.
- **최소 공통 메커니즘**: 주체 사이의 공유 상태를 줄이는 원칙이다.

</details>

```text
보안 설계 원칙
├─ 기본 거부•안전 실패
├─ 최소 권한•최소 기능
├─ 완전 중재•감사
├─ 단순•공개 메커니즘
└─ 권한 분리•공유 최소화
```

| 구성요소 | 책임 |
|:---|:---|
| 기본 거부•안전 실패 | 허용 근거•검사 실패 시 거부 |
| 최소 권한•최소 기능 | 자원•행위•시간 범위 제한 |
| 완전 중재•감사 | 모든 접근의 현재 정책 검사 |
| 단순•공개 메커니즘 | **메커니즘 경제성**•**공개 설계** 적용 |
| 권한 분리•공유 최소화 | **권한 분리**•**최소 공통 메커니즘** 적용 |

#### 한줄 요약

- 보호 자산별 **기본 동작·권한·검사점** 설계

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정책 집행점**: 접근 요청을 가로채 정책 결정을 실행하는 구성요소이다.
- **정책 결정점**: 현재 정책으로 접근 허용 여부를 판단하는 구성요소이다.
- **현재 권한•정책•맥락 구성**: 접근 판단에 필요한 최신 주체•대상•환경 정보를 모으는 단계이다.
- **기본 거부•최소 권한 판정**: 명시적 허용 근거와 필요한 최소 범위를 결정하는 단계이다.
- **허용 자원•행위•시간 제한**: 승인 결과를 구체적인 대상•동작•기간으로 축소하는 단계이다.
- **자원 행위•감사 증적 기록**: 집행 결과를 권한 회수와 책임 추적용으로 보존하는 단계이다.

</details>

```text
주체•대상•행위•맥락 요청
   │
   ▼
1. 현재 권한·정책·맥락 구성
   │
   ▼
2. 기본 거부·최소 권한 판정
   ├─ 허용 근거 없음 ──► 접근 거부
   └─ 명시적 허용
          │
          ▼
3. 허용 자원·행위·시간 제한
   │
   ▼
4. 자원 행위·감사 증적 기록
   │
   ▼
접근 결과
```

### 동작 원리

1. 현재 권한·정책·맥락 구성: 최신 판단 정보 구성
2. 기본 거부·최소 권한 판정: 명시된 범위만 허용
3. 허용 자원·행위·시간 제한: 정책 집행점 적용
4. 자원 행위·감사 증적 기록: 권한 회수 근거 생성

#### 한줄 요약

- 설정 누락·장애 시 **기본 거부 결과** 선결정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **안전 실패**: 보안 기능 장애 때 무단 접근 없는 상태로 전환하는 원칙이다.
- **장애 전환**: 장애 시 대체 시스템으로 서비스를 잇는 방식이다.
- **OT(Operational Technology) 안전 영향**: 보안 통제가 물리 공정에 미치는 결과이다.

</details>

| 실패•가용성 원칙 | 기본 거부 | 안전 실패 | 장애 전환 |
|:---|:---|:---|:---|
| 적용 기준 | 접근 정책 초기 상태 | 보안 통제 오류 상태 | 서비스 장애 대체 경로 |
| 핵심 특징 | **안전한 기본값**으로 거부 | **안전 실패**로 무단 접근 차단 | **장애 전환**으로 서비스 지속 |
| 한계 | 필수 업무 과도 차단 | **OT 안전 영향** | 약한 대체 경로의 우회 |

> 요약: 정책 누락, 보안 오류, 서비스 장애를 구분하는 것이 핵심이다.

#### 한줄 요약

- 기본 거부•안전 실패•장애 전환은 이름이 비슷해도 적용할 실패 상황이 다르다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **SP(Special Publication)**: NIST가 발행하는 특별간행물이다.
- **NIST SP 800-160**: 보안 시스템 수명주기 공학 지침이다.
- **NIST SP 800-53**: 시스템•조직 보안 통제 지침이다.
- **AC(Access Control)**: 접근 권한을 제한하는 통제군이다.
- **AU(Audit and Accountability)**: 감사•책임추적 통제군이다.
- **API(Application Programming Interface)**: 서비스 기능을 호출하는 연결 경계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 운영 단계에만 통제를 붙이면 설계 우회 경로 잔존 | **NIST**의 **SP**, **NIST SP 800-160** 적용 | 설계•운영 일관성 확보 |
| 상시 과권한으로 침해 시 피해 범위 확대 | **NIST SP 800-53**의 **AC** 적용 | 권한•기능•시간 축소 |
| 접근 근거가 없으면 허용 결정의 추적 불가 | **AU** 통제와 **API** 감사 연계 | 완전 중재•감사 확보 |

#### 한줄 요약

- 중요 API는 기본 거부하고 시간•기기•업무 조건을 매 요청 검사하며 권한 변경 시 캐시를 즉시 무효화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **심층 방어**: 독립 통제를 여러 계층에 적용해 단일 실패의 전체 확산을 막는 원칙이다.

</details>

- **심층 방어**로 모든 요청을 중재하고 실패 시 거부하되 안전 영향은 별도로 전환한다.

#### 한줄 요약

- 좋은 구조는 모든 실수를 막는 구조가 아니라 실수와 단일 실패의 영향을 제한하는 구조이다.
