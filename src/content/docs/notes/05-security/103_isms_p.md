## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **ISMS(Information Security Management System)**: 정보보호 위험과 통제를 관리하는 인증 체계이다.
- **ISMS-P(Personal Information & Information Security Management System)**: 개인정보보호 및 정보보호 관리체계 인증이다.
- **통합 관리체계**: 서비스 위험과 개인정보 수집•이용•제공•위탁•보유•파기의 책임을 하나의 범위에서 운영•심사하는 체계이다.

</details>

- 정의/개념: **ISMS**의 정보보호 요구와 개인정보 처리 요구를 함께 심사하는 **ISMS-P** **통합 관리체계** 인증이다.
- 배경/필요성: 분리된 점검만으로는 서비스 위험과 개인정보 처리 책임을 일관되게 연결하기 어렵다.

#### 한줄 요약

- 서비스 전체에서 위험 판단, 통제 운영, 개선 여부를 확인한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **인증 범위**: 심사할 서비스•조직•시스템과 운영 기간의 경계이다.
- **위험평가**: 범위 안의 자산•위협•취약점•개인정보 흐름을 분석하는 활동이다.
- **운영 증적**: 정책과 통제가 실제 작동했음을 보여 주는 로그•승인•점검•시정 기록이다.
- **3개 영역**: 관리체계 수립•운영, 보호대책, 개인정보 처리단계의 심사 구분이다.
- **102개 기준**: 16개 관리체계, 64개 보호대책, 22개 개인정보 요구사항이다.

</details>

- **3개 영역**의 **102개 기준**을 통합 심사한다.
- **위험평가** 결과에 따라 관리•물리•기술 통제를 선택한다.
- 로그•승인•점검•시정 기록을 **운영 증적**으로 관리한다.

#### 한줄 요약

- 일상 업무 기록을 심사 증거로 지속 관리한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **보호대책 요구사항**: 평가한 위험을 낮추기 위해 관리적•물리적•기술적 통제의 설계•운영 기준을 제시한 영역이다.
- **개인정보 처리단계**: 개인정보의 수집•이용•제공•위탁•보유•파기 각 과정에서 근거•권한•기록•종료를 통제하는 영역이다.

</details>

```text
ISMS-P 통합 관리체계
├─ 관리체계 수립 · 운영
│  └─ 범위 · 조직 · 정책 · 자원
├─ 위험관리
│  └─ 자산 · 위협 · 취약점 평가
├─ 보호대책 요구사항
│  └─ 관리 · 물리 · 기술 통제
├─ 개인정보 처리단계
│  └─ 수집부터 파기까지 보호
└─ 감사 · 지속 개선
   └─ 운영 기록 · 시정 · 재검증
```

| 구성요소 | 책임 |
|:---|:---|
| 관리체계 수립•운영 | **인증 범위**•조직•정책•자원 설정 |
| 위험관리 | **위험평가**와 처리 계획 수립 |
| 보호대책 요구사항 | **보호대책 요구사항**에 따른 관리•물리•기술 통제 |
| 개인정보 처리단계 | **개인정보 처리단계**별 생명주기 보호 요구 |
| 감사•지속 개선 | **운영 증적**과 시정•재검증 반복 |

#### 한줄 요약

- 서비스 경계 안의 위험과 개인정보 흐름을 통제로 묶어 개선한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **심사 발견사항**: 통제의 부적합과 운영 결함을 증거로 확인한 결과이다.
- **시정조치**: 발견사항의 근본 원인을 제거해 재발을 막는 개선 활동이다.
- **위험-통제-증적 연결**: 식별 위험과 선택한 보호대책, 실제 운영 결과를 일대일로 추적하여 심사 가능하게 하는 구조이다.
- **인증 범위•정책 확정**: 심사할 서비스•조직•시스템과 관리 정책을 정하는 단계이다.
- **자산•위협•위험 평가**: 범위 안의 자산•위협•취약점과 개인정보 흐름을 분석하는 단계이다.
- **보호대책•개인정보 통제**: 평가 위험과 처리단계에 맞는 통제를 수행하는 단계이다.
- **운영 증적•심사 자료 구성**: 통제 결과를 서면•현장 심사에 사용할 근거로 정리하는 단계이다.
- **발견사항 원인•시정 결정**: 부적합의 근본 원인을 제거하고 통제를 갱신하는 단계이다.

</details>

```text
1. 인증 범위•정책 확정
              │
              ▼
2. 자산•위협•위험 평가
              │
              ▼
3. 보호대책•개인정보 통제
              │
              ▼
4. 운영 증적•심사 자료 구성
              │
              ▼
         심사 발견사항
              │
              ▼
5. 발견사항 원인•시정 결정
              │
              └──── 통제 갱신 ────┐
                                  └─ 위험 평가로 환류
```

### 동작 원리

1. **인증 범위•정책 확정**: 서비스•조직•시스템 경계를 설정한다.
2. **자산•위협•위험 평가**: 위험 식별•분석•처리 계획을 수립한다.
3. **보호대책•개인정보 통제**: 기준별 통제 수행•결과를 기록한다.
4. **운영 증적•심사 자료 구성**: **위험-통제-증적 연결**에 따라 통제 근거를 정리한다.
5. **발견사항 원인•시정 결정**: **심사 발견사항**의 원인을 제거하는 **시정조치**를 정한다.

#### 한줄 요약

- 위험 평가 결과와 실제 통제 기록을 심사하고 결함을 고친다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

</details>

| 국내 관리체계 인증 | ISMS | ISMS-P |
|:---|:---|:---|
| 적용 기준 | **ISMS** | **ISMS-P** |
| 핵심 특징 | 정보보호 관리체계 요구 | **3개 영역**•**102개 기준** 통합 |
| 한계 | 개인정보 기준 별도 확인 | 인증 범위 밖 서비스 보장 불가 |

#### 한줄 요약

- ISMS-P는 ISMS에 개인정보 처리단계 22개 기준을 더한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **정보통신망법 제47조**: 정보보호 관리체계 인증의 법적 근거를 규정한 조항이다.
- **개인정보 보호법 제32조의2**: 개인정보보호 관리체계 인증과 유효기간을 규정한 조항이다.
- **ISMS-P 세부 기준**: 인증 범위 안에서 관리체계•보호대책•개인정보 처리단계별 통제 누락을 확인하는 심사 기준이다.
- **API(Application Programming Interface)**: 서비스 기능과 데이터를 정해진 요청•응답 형식으로 제공하는 경계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정보보호 인증 근거 | **정보통신망법 제47조** 적용 | 법정 의무•대상 확인 |
| 개인정보 인증 근거 | **개인정보 보호법 제32조의2** 적용 | 인증•유효기간 확인 |
| 세부 심사 기준 | **ISMS-P 세부 기준**과 **102개 기준** 점검 | 통제 누락 방지 |

#### 한줄 요약

- 클라우드•외부 **API**•위탁 조직까지 실제 서비스 경계를 추적한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **인증 범위 한계**: 인증이 명시된 서비스•조직•시스템과 기간의 통제 운영만 보장하여 범위 밖 클라우드•위탁•API를 별도 확인해야 하는 제약이다.

</details>

- **인증 범위 한계**를 확인하고 정보보호 통제는 **ISMS**, 개인정보 처리단계 포함 시 **ISMS-P**를 선택한다.

#### 한줄 요약

- 인증 범위의 위험과 개인정보 흐름을 기록으로 계속 개선한다.
