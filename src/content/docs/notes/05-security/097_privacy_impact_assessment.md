## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PIA (Privacy Impact Assessment / 개인정보 영향평가)**: 수백만 명의 개인정보파일을 시스템에 RDB로 새롭게 구축하거나 대규모로 변경 연결하기 전에, 정보가 흘러가는 모든 파이프라인 흐름의 침해 폭발 위험을 선제적으로 해부 분석하고, 서비스 오픈 전 뜯어고칠 필수 개선사항을 도출해 내는 국가 공인 법정 의무 평가 팩트이다.
- **사전 평가 설계 원칙 (Privacy by Design / 사전 평가)**: 코딩 다 끝나고 시스템이 완성 런칭된 후 사후약방문으로 땜질하는 것이 아니라, 아키텍처 설계 도면 단계에서 개인정보 DB 흐름과 스키마 구조를 갈아엎을 수 있는 가장 뼈대 시점에 치명적 위험을 먼저 찾아내어 막대한 개발 재작업 비용 손실을 0으로 줄이는 선제 통제 팩트 원칙이다.

</details>

- 정의: 대규모 개인정보 시스템을 신규 **구축**하거나 기존 통신망 구조를 확 **변경**하기 전에, 데이터가 흐르는 모든 혈관의 처리 흐름과 유출 침해 위험을 선제적으로 해부 검사하는 **사전 예방적 의무 평가 절차 팩트**이다.
- 배경: 일단 막대한 비용을 들여 DB와 시스템 코딩이 100% 완성 런칭된 뒤에, 늦게 보안 구멍을 발견하여 개인정보 API 흐름과 RDB 스키마 구조를 갈아엎으려면 천문학적인 재개발 비용과 서비스 셧다운 피해가 발생하기 때문이다.

#### 한줄 요약

- 거대 시스템을 코딩하고 만들기 전에, 개인정보가 핏줄처럼 흘러다니는 모든 파이프라인 길을 도면에서 샅샅이 찾아내 가장 위험한 유출 경로와 엉성한 설계를 서비스 오픈 전 사전에 뜯어고쳐버리는 선제 방어 팩트 절차이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **개인정보 흐름도 (Data Flow Diagram)**: 최초 수집 화면부터 저장 RDB, 이용 부서망, 제3자 외부망 API 제공, 야간 백업 LTO 테이프, 일일 개발 로그, 그리고 최종 Delete 파기 시점까지 데이터가 굴러가는 전 생애 이동 경로와 책임 통제 주체를 시각적으로 모조리 매핑해 놓은 해부 도식 팩트이다.
- **구체적 개선조치 계획 (Actionable Mitigation Plan)**: 막연히 '보안을 강화해라'라는 뜬구름 잡는 소리가 아니라, 어느 시스템의 어떤 침해 위험을 줄이기 위해 '방화벽 룰셋 80포트 통제'를 '개발팀장 홍길동'이 '10월 30일'까지 구축하고, '방화벽 설정 캡처 화면'이라는 완료 증거로 증명하라는 식의 치밀한 팩트 액션 플랜이다.
- **승인된 잔여 위험 (Accepted Residual Risk)**: 개선조치 철조망을 다 치고 나서도, 서비스 본질상 어쩔 수 없이 감수하고 안고 가야 하는 남아있는 위험 찌꺼기를, 경영진 CPO가 최종 결재 도장 찍어 승인하고 365일 감시망에 올리는 통제 팩트 위험이다.

</details>

- **핏줄 해부도 기반 전수 분석**: 텍스트 명세서가 아니라 핏줄 같은 **개인정보 흐름도**를 바탕으로, 메인 DB뿐 아니라 숨겨진 백업 복제본 경로의 전 범위를 샅샅이 팩트로 해부 분석한다.
- **액션 플랜 팩트 결속**: 뜬구름 잡는 권고가 아니라, 명확한 **개선조치**에 타겟 위험·담당자·데드라인 기한·완료 증빙 스크린샷 증거를 1:1 하드 매핑 연결한다.
- **변경 시 무한 루프 재평가 및 잔여 위험 승인**: 나중에 외부 API가 하나라도 변경 추가되면 평가 범위를 리셋 갱신하고, 다 쳐내고도 남은 **잔여 위험** 찌꺼기를 경영진 CPO에게 팩트로 다시 결재 승인받는다.

#### 한줄 요약

- 두꺼운 보고서 책자 작성에 그치지 않고, "어느 DB 테이블의 어떤 해킹 위험을, 보안팀 누가, 며칠까지 코드 뜯어고쳐 막고, 무슨 스크린샷으로 완료 증거를 입증할지"를 무관용으로 하드 연결하는 실전 팩트 특성이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **타겟 평가 범위 (Assessment Scope)**: 평가하겠다고 칼을 댈 대상 범주로, 메인 개인정보파일 테이블은 물론이고, 앞단 WAS 시스템, 뒷단 외부 통신 연계 API, 거미줄처럼 복제된 로그 파일 경로까지 일망타진하는 범위 팩트이다.
- **치명적 침해요인 (Privacy Threats / Vulnerability)**: 해커 침투나 내부자 유출 시 개인정보의 기밀성 붕괴, 무결성 변조 훼손, 랜섬웨어로 인한 가용성 마비에 심각한 타격을 주는 위협 시나리오 및 시스템 보안 취약점 팩트이다.
- **실물 이행 증거 (Implementation Evidence)**: 평가관이 하라고 지시한 개선 항목이 단순 정책서 한 줄 타이핑이 아니라, 실제 물리적 DB 설계 스키마, 소스코드 커밋 내역, 방화벽 차단 설정, 현업 운영 매뉴얼 등 눈에 보이는 실물 세계에 100% 반영 반영됐음을 빼도 박도 못하게 입증하는 서류 팩트 자료이다.

</details>

```text
[개인정보 보호법정 의무 사전 영향평가(PIA) 해부 및 통제 팩트 구조]

├─ [1. 전장 타겟 범위 설정 경계]
│    └─ [수집 규모 대상 산정 및 평가 법적 근거 확립]
│
├─ [2. 해부 및 치명적 위험 분석 경계]
│    ├─ [데이터 전주기 핏줄 처리 흐름도 및 아키텍처 구조 해부]
│    └─ [내외부 침해요인 발굴 및 재무적 위험도 레벨 산정]
│
└─ [3. 무관용 개선 집행 및 경영진 최종 승인 경계]
     ├─ [담당자/기한 맵핑 핀셋 개선계획 액션 플랜 수립]
     └─ [실물 코드 이행 증거 검증 및 CPO 잔여위험 최종 승인 결재]
```

| 구성요소 | 핵심 보안 해부 책임 및 통제 팩트 역할 |
|:---|:---|
| **대상 및 법적 근거 스코프** | **타겟 평가 범위**의 대상 파일 규모, 관련 시스템 서버, 외부 연계 API망을 도마 위에 확정 고정 |
| **핏줄 처리 흐름 및 시스템 구조** | **개인정보 데이터 흐름도** 도면 위에 최초 수집부터 몰래 복제, 외부 제공, 완전 파기 라인까지 핏줄 표시 |
| **침해요인 및 위험도 타격 산정** | 도출된 **침해요인**의 현실적 해킹 위협, 방어망 취약점, 유출 시 징벌 과징금 재무 영향 레벨 팩트 산정 |
| **핀셋 개선계획 액션 플랜** | 도출된 **개선조치**에 방화벽 통제 등 구체적 솔루션, 담당 실명, 완료 기한, 검증 증거 기준을 락킹 설정 |
| **이행 증거 검증 및 잔여 승인** | 소스코드 등 **실물 이행 증거** 검증 확인 사살과, 안고 갈 수밖에 없는 **잔여 위험**에 대한 CPO 승인 결재 팩트 |

#### 한줄 요약

- 메인 데이터베이스 덩어리뿐만 아니라 숨겨진 야간 백업망, 일일 텍스트 로그, 타사 외부 연계 API의 은밀한 개인정보 흐름까지 일망타진 포함해, 발굴된 위험과 방어 코드를 1:1 매핑 연결하는 팩트 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **리스크 위험도 정량 산정 (Risk Scoring)**: 유출 침해 사건이 터질 끔찍한 '발생 가능성' 곱하기 터졌을 때의 대규모 과징금 '파멸적 재무 영향', 그리고 현재 발라져 있는 '기존 보안 통제 쉴드' 수준을 산술적으로 함께 정량 평가하여, 당장 내일 고쳐야 할 개선 0순위와 감수할 수용 여부를 칼같이 정하는 수학적 과정 팩트이다.
- **운용 변경 리셋 재평가 (Change Re-assessment)**: 처음 평가를 통과했어도, 나중에 외부 스타트업 API 연동 하나 새로 뚫리거나, 마케팅 처리 목적이 몰래 추가되거나, 파일 회원 수 규모가 두 배 폭증하는 등 기존 운용체계 뼈대가 흔들리며 바뀔 때 기존 영향평가 면죄부를 휴지통에 버리고 위험을 백지에서 다시 확인하는 무자비한 절차 팩트이다.
- **법정 타겟 대상 및 평가 범위 확정 단계**: DB 파일 규모 100만 명 초과 여부, 민감 정보 유형 포함 여부, 대규모 외부망 연계를 확인해, 국가에 제출할 의무 평가 대상인지 스코프를 확정 팩트로 정하는 진입 단계이다.
- **데이터 흐름 해부 및 보호 현황 스캔 단계**: 수집 목적 적법 근거, 어둠의 복제 경로, 현재 발려진 방화벽/암호화 등 기존 보호 쉴드 조치 현황을 엑스레이 분석하는 단계이다.
- **치명적 침해요인 및 타격 위험도 산정 단계**: 뚫릴 가능성, 터지면 닥칠 과징금 파멸적 영향, 기존 통제 방어력을 공식에 넣어 팩트 평가하는 단계이다.
- **개선조치 코드 구현 및 실물 증거 생성 단계**: 평가관 지적 담당과 기한에 따라 방어 통제 로직을 시스템 코드에 팩트 반영하고, 캡처 화면이나 커밋 로그 완료 서류를 만드는 집행 단계이다.
- **잔여위험 CPO 승인 및 변경 락킹 관리 단계**: 다 고치고도 남은 찝찝한 잔여 위험 찌꺼기를 경영진이 도장 찍어 책임 승인하고, 향후 운용체계 변경 스위치 켜질 때 재평가 사이클을 가동하는 통제 유지 단계이다.

</details>

```text
[신규 시스템 설계 도면, 메인 DB 파일 규모 타겟, 운영 환경 아키텍처 자료 투입]
                  |
                  v
1. 의무 법정 대상 100만명 등 규모 컷 확인 및 타겟 평가 범위 스코프 확정 팩트
                  |
                  v
2. 전주기 데이터 처리 핏줄 흐름 해부 및 현재 적용된 암호화 등 보호 현황 엑스레이 스캔
                  |
                  v
3. 보안 구멍 침해요인 타겟 발굴 및 과징금 폭탄 규모를 반영한 정량적 위험도 스코어 팩트 산정
                  |
                  v
4. 우선순위 기반 개선조치(방화벽/코드) 실제 시스템 구현 방어 및 캡처/커밋 실물 증거 팩트 생성
                  |
                  v
5. 찌꺼기 잔여위험 CPO 최고책임자 승인 결재 및 향후 외부 API 변경 등 발생 시 무한 재평가 리셋 관리
                  |
                  v
       [보호위 등 국가 기관 관청에 최종 영향평가 결과서 제출 및 방어 팩트 입증]
```

### 동작 원리

1. 타겟 대상·범위 확정: 법이 정한 인원수 파일 규모·민감 유형·외부망 연계 컷을 확인한다.
2. 핏줄 흐름·보호 스캔: 수집 목적 근거와 뒷구멍 복제 경로, 기존 쉴드를 해부 분석한다.
3. 침해요인·위험도 스코어링: 해킹 뚫릴 가능성·유출 과징금 영향력·현재 방어력 공식을 돌린다.
4. 개선 코드 구현·증거 창출: 지적된 방어 로직을 코드에 반영하고 빼도 박도 못할 완료 캡처 자료를 생성한다.
5. 잔여 승인·변경 무한 리셋: 남은 위험은 CPO가 결재하고, 시스템 뼈대가 바뀌면 재평가 루프를 돌린다.

#### 한줄 요약

- 전쟁 전 스코프 범위와 핏줄 데이터 흐름을 정한 뒤 뚫릴 타격 위험을 정량 계산하고, 개선 보안 결과가 기획서가 아닌 실제 DB 설계·소스코드·운영 캡처 기록에 눈으로 팩트 반영됐는지를 증거로 확인 사살한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **초민감 민감정보 파일 (Sensitive Data File)**: 해킹 노출 시 사상, 병력, 유전자 등 인간 사생활 침해에 파멸적 재앙을 초래하는 민감정보가 5만 명 이상 담겨 국가가 의무 평가로 강제하는 고위험 개인정보파일 팩트이다.
- **고유식별정보 파일 (Unique ID Data File)**: 한 번 유출되면 바꿀 수도 없는 주민등록번호, 여권번호 등 국가가 부여해 개인을 고유하게 식별하는 치명적 정보를 5만 명 이상 처리하는 폭탄 파일 팩트이다.
- **거미줄 연계 파일 (Linked Data File)**: A기관 파일 50만 명분과 B기관 외부 파일을 거미줄처럼 API로 망 연결해 100만 명분으로 결합해 버리면 식별성이 폭증하므로 강제 평가를 받는 연계 파일 팩트이다.
- **초대규모 대규모 파일 (Large-scale Data File)**: 민감정보가 없더라도, 그냥 머릿수 자체가 법정 기준 100만 명분 이상으로 무지막지하게 많아서 해킹 한 방에 국가적 재난이 터지는 개인정보파일 팩트이다.

</details>

|:---|:---|:---|:---|

#### 한줄 요약

- 공공기관 및 대규모 사업자는 사생활 타격 민감성 규모(5만), 타사 거미줄 연계 결합 규모(100만), 단일 머릿수 전체 규모(100만), 그리고 기존 면죄부 평가 후 시스템 뼈대 운용체계 변경 여부 중 하나라도 걸리면 법정 강제 평가 대상 통제 팩트로 판단된다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **보호법 제33조 (PIPA Art. 33 - PIA Mandate)**: 나랏돈 쓰는 공공기관은 시스템 구축 전 반드시 국가 지정 법정 영향평가를 실시해 보호위 관청에 결과 제출을 의무로 쐐기 박고, 전문 평가기관 하청 의뢰 절차를 강제 규정한 팩트 조항이다.
- **시행령 제35조 (Enforcement Decree Art. 35 - Scope Limits)**: 아무 파일이나 평가하는 게 아니라, 의무 영향평가 대상 개인정보파일의 5만 명 민감성 타겟 컷, 100만 명 연계 결합 규모 컷, 100만 명 대규모 컷, 그리고 운용체계 변경 리셋 발동 팩트 기준을 숫자로 칼같이 규정한 조항이다.
- **외부 융합 AI API (Artificial Intelligence API)**: 챗GPT처럼 외부로 데이터를 뿜어내어 학습된 블랙박스 모델로 인식·추론·생성 마법 작업을 수행하는 거대 클라우드 기술로, 붙이는 순간 내 DB의 수많은 데이터가 밖으로 줄줄 새어 나가는 최악의 신종 제공 경로 팩트이다.

</details>

| 서비스 오픈 장애/유출 폭탄 위험 요소 | 근본 원인 취약점 팩트 분석 | 최정예 실무 방어 대책 및 팩트 해결방안 | 기대 철벽 통제 쉴드 효과 |
|:---|:---|:---|:---|

#### 한줄 요약

- 멀쩡히 돌아가던 공공 시스템에 멋부리려고 외부 챗GPT 같은 AI 연동 API를 한 줄 추가하는 순간, 데이터가 밖으로 새 나가는 거대한 '새 제공·복제 경로'가 뚫린 '운용체계 변경(리셋 발동)' 사태에 해당하므로, 즉각 과거 서류를 찢어버리고 영향 범위와 잔여 타격 위험을 백지에서 무관용 재평가 팩트로 돌려야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **진정한 PIA 완료 조건 (True PIA Completion Criteria)**: 허울 좋은 두꺼운 보고서 책자 인쇄 후 관청 우체국 제출 시점이 끝이 아니라, 평가관이 지적한 개선 방어 항목의 실제 소스코드 하드코딩 구현 팩트 증거 검증 완료, 찝찝한 잔여 위험에 대한 CPO의 독박 승인 결재 도장, 그리고 훗날 API 변경 시 자동 무한 재평가 루프 체계 셋업까지 모두 100% 톱니바퀴처럼 갖춰진 궁극의 팩트 상태이다.

</details>

- 시스템 오픈을 위한 단순 서류 작업 통과가 본질이 아니므로, **진정한 PIA 완료 조건**의 무관용 원칙에 따라 법정 범위 핏줄망 전체의 **PIA**를 혹독하게 수행하고 실제 핀셋 코딩 개선 조치 완료 뒤, 남은 찌꺼기 **잔여 위험**을 최고책임자가 팩트 승인 결재한다.

#### 한줄 요약

- 개인정보 영향평가의 진정한 보안 팩트는 탁상행정 보고서 제출에서 끝나는 것이 절대 아니라, 지적받은 방어 개선 항목 코드가 실제 DB 설계망과 운영 서버에 하드코딩 반영 입증되고, 훗날 외부 연동 변경 뒤에도 위험 재평가 무한 루프가 자동 관리되는 치열한 사전 통제 절차 팩트 필수.
