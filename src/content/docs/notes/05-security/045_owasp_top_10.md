## 미리 알고가기

- **OWASP (Open Worldwide Application Security Project)**: [읽기: 오더블유에이에스피; 표기 이유: 영문 머리글자] 공개 웹·응용 보안 지침과 도구를 개발하는 비영리 프로젝트
- **OWASP Top 10**: [읽기: 오더블유에이에스피; 표기 이유: 영문 머리글자] 반복되는 웹 위험 범주 10개
- **ASVS (Application Security Verification Standard)**: [읽기: 에이에스브이에스; 표기 이유: 영문 머리글자] 응용 보안 요구사항과 검증 수준을 제시하는 표준
- **WSTG (Web Security Testing Guide)**: [읽기: 더블유에스티지; 표기 이유: 영문 머리글자] 웹 보안 시험 항목과 절차를 제시하는 지침
- **XXE (XML External Entity)**: [읽기: 엑스엑스이; 표기 이유: 영문 머리글자] XML 외부 엔터티 참조로 파일 읽기·내부망 요청을 유도하는 공격
- **SSRF (Server-Side Request Forgery)**: [읽기: 에스에스알에프; 표기 이유: 영문 머리글자] 서버가 공격자가 지정한 내부·외부 주소로 요청하게 만드는 공격
- **SDLC (Software Development Life Cycle)**: [읽기: 에스디엘씨; 표기 이유: 영문 머리글자] 요구·설계·개발·시험·배포·운영의 소프트웨어 수명주기
- **핵심 판단**: [읽기: 핵심 판단; 표기 이유: 한국어 통용어 표기] Top 10은 인식 자료이며 검증 표준이 아님




- **흐름 기호(↓·→·X)**: [읽기: 흐름 기호; 표기 이유: 한글명 뒤 영문 원어 병기] 아래로·다음으로·차단으로 읽으며 순서·분기·금지를 나타냄
## Ⅰ. 개요

- **정의/개념**: 주요 웹 애플리케이션 위험 범주임
- **배경/필요성**: 웹 위험을 통제로 바꿀 공통 언어가 필요함

### 쉽게 이해하기 (학습용)

- 반복되는 웹 위험을 공통 언어로 묶어 보안 요구와 시험으로 연결한다.

## Ⅱ. 특징

- 원인과 영향이 연관된 웹 위험 범주를 제시한다.
- 전문가 검토와 자료를 반영해 판마다 범주를 갱신한다.
- 보안 인식과 우선순위 논의의 출발점으로 쓴다.
- 요구사항·시험 절차·준수 인증을 대신하지 못한다.

### 쉽게 이해하기 (학습용)

- 위험 목록을 ASVS 요구와 WSTG 시험으로 구체화해야 한다.

## Ⅲ. 구성요소 및 구조

| 설계 요소 | 핵심 내용 |
|:---|:---|
| 접근 구성 | A01 접근 통제·A02 구성 오류 |
| 공급 암호 | A03 공급망 실패·A04 암호화 실패 |
| 입력 설계 | A05 인젝션·A06 불안전한 설계 |
| 인증 무결 | A07 인증 실패·A08 무결성 실패 |
| 운영 예외 | A09 로깅/경보·A10 예외 처리 |

```text
Top 10 (위험)
  ├─ ASVS (요구)
  └─ WSTG (시험)
       ↓
SDLC 피드백
```

### 쉽게 이해하기 (학습용)

- Top 10 위험을 ASVS 통제와 WSTG 시험에 연결해 수명주기에 반영한다.

## Ⅳ. 원리 및 절차 흐름도

```text
범위선택
   ↓
위험매핑
   ↓
기준구체
   ↓
구현검증
   ↓
운영환류
```

| 절차 | 설명 |
|:---|:---|
| 범위선택 | 적용할 Top 10 판과 경계 정함 |
| 위험매핑 | 기능과 의존성을 위험 범주에 연결함 |
| 기준구체 | ASVS 기준으로 통제 항목 정의함 |
| 구현검증 | 설계·코드 검사와 보안 검증 실행함 |
| 운영환류 | 사고와 변경 결과 요구사항에 반영함 |

> 요약: 위험 매핑 기반의 검증과 운영 환류

### 쉽게 이해하기 (학습용)

- 적용 판과 범위를 정한 뒤 위험별 요구·시험·운영 지표를 연결한다.

## Ⅴ. 종류 및 비교

| 비교축 | Top 10 | ASVS | WSTG |
|:---|:---|:---|:---|
| 핵심 특징 | 주요 웹 위험 범주를 제시 | 보안 요구사항·검증 수준 제시 | 웹 보안 시험 방법·절차 제시 |
| 적용 기준 | 주요 웹 위험을 인식할 때 | 보안 요구사항·수준을 정할 때 | 웹 보안 시험 절차가 필요할 때 |
| 주요 위험 | 단순 체크리스트·준수 인증으로 오용 | 범위·수준을 과도하게 적용 | 시험 절차만 수행하고 원인 수정 누락 |

### 쉽게 이해하기 (학습용)

- Top 10은 위험 인식, ASVS는 요구, WSTG는 시험에 사용한다.

## Ⅵ. 실무 사례

- Top 10 범주를 단일 탐지 규칙으로 보지 않음
- ASVS 요구사항과 WSTG 검증을 추적 가능하게 연결함
- 공급망·구성·운영 위험을 코드 검사만으로 종결하지 않음
- 판 변경 시 기존 통제와 새 범주의 공백을 재분석함
- XXE는 외부 참조를 끄고 파일·망 접근을 제한함
- SSRF는 주소·DNS·리다이렉트를 재검증하고 송신을 제한함
- 인증 후 객체·행위별 서버 인가를 다시 검증함
- 민감정보는 수집·복제·보존을 줄이고 상태별로 보호함

### 쉽게 이해하기 (학습용)

- Top 10 범주를 하나의 탐지 규칙으로 오해하지 않는다.
- ASVS 요구와 WSTG 검증 결과를 추적 가능하게 잇는다.
- 공급망·구성 위험을 코드 검사만으로 종결하지 않는다.
- 판이 바뀌면 기존 통제와 새 범주의 공백을 재분석한다.
- XXE는 외부 참조와 파일·망 접근을 제한한다.
- SSRF는 주소·DNS·재지정을 검증하고 송신을 제한한다.
- 인증 뒤에도 객체·행위별 서버 인가를 다시 확인한다.
- 민감정보의 수집·복제·보존을 줄이고 상태별 보호한다.

## Ⅶ. 결론

- Top 10을 ASVS 요구와 WSTG 시험으로 구체화함

### 쉽게 이해하기 (학습용)

- Top 10은 체크리스트가 아니라 요구와 시험을 정하는 출발점이다.
