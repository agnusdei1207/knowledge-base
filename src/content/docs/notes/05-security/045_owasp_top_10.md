## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **OWASP Top 10(Open Worldwide Application Security Project Top 10)**: 전 세계 수백만 건의 실제 웹 애플리케이션 침해사고 데이터와 전문가 합의를 기반으로, 웹 환경에서 가장 빈번하게 발생하고 비즈니스 파급력이 치명적인 상위 10가지 보안 위험 범주를 표준화하여 제시하는 글로벌 웹 보안 참조 모델.
- **OWASP 보안 삼각 체계(OWASP Security Triad)**: 위험 식별(What: **OWASP Top 10**) $\rightarrow$ 안전한 설계 및 요구사항 정의(How to Build: **ASVS**) $\rightarrow$ 체계적 테스트 및 모의 침투 검증(How to Test: **WSTG**)으로 이어지는 엔드투엔드 시큐어 SDLC 프레임워크.

</details>

- 정의/개념: 웹 개발 및 운영 환경에서 발생하는 취약점을 **10대 핵심 위험 범주로 구조화**하고, 보안 요구사항 표준인 **ASVS(Application Security Verification Standard)** 및 테스트 지침인 **WSTG(Web Security Testing Guide)** 와 유기적으로 연계하여 소프트웨어 개발 생애주기(SDLC) 전반의 보안성을 내재화하는 **웹 보안 거버넌스 아키텍처**
- 배경/필요성: 단편적인 소스코드 버그 목록에만 의존할 경우 개발팀이 비즈니스 위험에 직결된 핵심 취약점의 우선순위를 판별하지 못하고, 단순 체크리스트식 대응으로 인해 근본적인 아키텍처 결함을 방치하는 한계를 극복할 요구

#### 한줄 요약
- 10대 웹 위험 범주(Top 10)를 식별하고, ASVS 설계 규격과 WSTG 검증 지침을 결합하여 시큐어 SDLC를 완성한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ASVS(Application Security Verification Standard)**: 웹 애플리케이션 및 웹 서비스(API)의 보안 아키텍처를 수립할 때 요구되는 세부 보안 통제 항목을 3단계 레벨(Level 1 자동 검증 가능, Level 2 대부분의 엔터프라이즈 앱 권장, Level 3 금융/군사 핵심 시스템)로 정의한 명세서.
- **WSTG(Web Security Testing Guide)**: 웹 애플리케이션의 구현 결함을 식별하기 위해 모의 침투 테스터와 품질 관리자가 따라야 할 표준 침투 테스트 절차 및 체크리스트 가이드.

</details>

- **통계 및 실증 기반 위험 범주화**: 실제 글로벌 취약점 데이터셋과 산업계 전문가 설문을 융합하여 3~4년 주기로 순위 최적화
- **아키텍처 중심 결함 강조**: 단순 구문 오류(Syntax)를 넘어 접근 통제 붕괴(Broken Access Control), 안전하지 않은 설계(Insecure Design) 등 상위 설계 결함 집중
- **Shift-Left 시큐어 SDLC 연동성**: 요구사항 분석(Top 10) $\rightarrow$ 설계/구현(ASVS) $\rightarrow$ 검증/테스트(WSTG)로 이어지는 완결된 방법론 제공

#### 한줄 요약
- 통계 기반 10대 범주화, 아키텍처 결함 중심 통제, ASVS 설계 및 WSTG 검증 연계를 통한 Shift-Left 구현을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **최신 OWASP Top 10 핵심 범주**:
  - **A01: Broken Access Control (접근 통제 붕괴)**: 비인가 IDOR 및 권한 상승.
  - **A02: Cryptographic Failures (암호화 실패)**: 평문 전송 및 취약 알고리즘.
  - **A03: Injection (인젝션)**: SQLi, NoSQLi, OS Command Injection.
  - **A04: Insecure Design (안전하지 않은 설계)**: 위협 모델링 부재로 인한 아키텍처 결함.
  - **A05: Security Misconfiguration (보안 설정 오류)**: 디폴트 계정 및 불필요한 포트 개방.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 위험 식별 및 거버넌스: OWASP Top 10 ]                              │
│  └─ 전사 웹 애플리케이션 10대 치명적 위협 범주 매핑 (A01~A10)           │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (SDLC 기획/설계 단계: 보안 요구사항 주입)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 보안 요구사항 및 아키텍처 설계: OWASP ASVS 4.0 ]                   │
│  ├─ Level 1: 기회주의적 공격 방어 (자동 스캐너 검증 기준)               │
│  ├─ Level 2: 엔터프라이즈 민감 데이터 보호 (BOLA/인젝션 방어 설계)      │
│  └─ Level 3: 금융/국방 미션 크리티컬 트랜잭션 무결성 강제               │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (SDLC 개발 단계: 시큐어 코딩 구현)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 소스코드 구현 및 정적 검증 (SAST / SCA) ]                          │
│  └─ 파라미터화 쿼리(PreparedStatement), 입력값 화이트리스트 검증 구현   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (SDLC 테스트/배포 단계: 침투 검증)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 보안 검증 및 동적 모의 침투: OWASP WSTG 4.2 ]                     │
│  ├─ 표준 테스트 케이스(WSTG-INPV, WSTG-ATHZ 등) 기반 자동/수동 진단     │
│  └─ [ 취약점 발견 시 개발팀 피드백 ➔ 미발견 시 프로덕션 배포 승인 ]     │
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: Top 10에서 위험을 식별하고 ASVS 명세를 설계에 반영하여 시큐어 코딩을 수행한 후, WSTG 절차에 따라 최종 침투 검증을 완료하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **OWASP Top 10** | 전 세계 웹 보안 침해 통계를 바탕으로 상위 10대 위험 범주 및 우선순위 제시 | Risk Awareness |
| **OWASP ASVS** | 애플리케이션 설계 및 아키텍처에 내재화해야 하는 3단계 보안 요구사항 명세화 | Architecture Spec|
| **시큐어 코딩 (SAST/SCA)** | 개발자가 소스코드 레벨에서 인젝션, XSS, 취약 라이브러리 결함을 원천 방어 | Implementation |
| **OWASP WSTG** | 배포 전 단계에서 취약점이 완전히 통제되었는지 검증하는 표준 모의 침투 지침 | Verification |
| **위협 모델링 (Threat Model)**| 설계 초기 단계에서 데이터 흐름도(DFD)를 분석하여 안전하지 않은 설계(A04) 방지 | Shift-Left |

#### 한줄 요약
- OWASP Top 10(위험), ASVS(설계 규격), 시큐어 코딩(구현), WSTG(검증 지침), 위협 모델링이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **ASVS 레벨 선정 기준**:
  - **Level 1**: 모든 소프트웨어의 최소 기준선 (Black-box 스캔 통과 수준)
  - **Level 2**: PII(개인정보) 및 비즈니스 트랜잭션을 처리하는 일반 엔터프라이즈 앱
  - **Level 3**: 군사, 의료 기기, 금융 코어 뱅킹 등 최고 등급 무결성 요구 시스템

</details>

```text
1. [위험 식별] 서비스 비즈니스 특성(예: 전자상거래 웹)을 OWASP Top 10(A01 권한 붕괴, A03 인젝션)에 매핑
            │
            ▼
2. [보안 요구 명세화] 아키텍처 설계 단계에서 OWASP ASVS Level 2(엔터프라이즈) 세부 항목을 설계서에 반영
            │
            ▼
3. [시큐어 코딩 구현] ORM 매핑, 파라미터화 쿼리, 세션 기반 RBAC(Role-Based Access Control) 코드 구현
            │
            ▼
4. [CI/CD 자동 검증] Git Commit 시 SAST/DAST 파이프라인이 구동되어 1차 취약점 자동 필터링
            │
            ▼
5. [WSTG 표준 모의 침투] 스테이징 환경에서 보안 담당자가 WSTG 테스트 케이스에 입각한 침투 검증 집행
            │
            ├─ [취약점 검출 시] ➔ 배포 파이프라인 차단 및 개발팀에 ASVS 코드 수정 요구
            ▼
6. [안전 배포 및 환류] 10대 위험 전 항목 방어 입증 완료 ➔ 프로덕션 릴리즈 및 런타임 WAF 모니터링
```

**동작 원리**

1. **위험 기반 우선순위 배분**: 무차별적 결함 검토 대신 10대 고위험군에 개발 리소스 집중
2. **명문화된 보안 아키텍처**: 모호한 보안 가이드 대신 ASVS의 명확한 체크 항목 적용
3. **선제적 결함 억제**: 취약점이 빌드/배포 단계로 전파되기 전 코드 레벨에서 차단
4. **표준화된 검증 재현성**: 점검자의 주관적 판단을 배제하고 WSTG의 구조화된 시험 절차 준수
5. **폐쇄 루프 품질 보증**: 침투 테스트 통과 증적을 확보한 아티팩트만 운영망 승인

#### 한줄 요약
- Top 10 매핑, ASVS 요구 명세, 시큐어 코딩 구현, CI/CD 자동 검증, WSTG 모의 침투, 안전 배포 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **OWASP 3대 표준 도구 비교**: Top 10(위험 분류), ASVS(요구사항 명세), WSTG(테스트 지침)의 비교.

</details>

| 비교 항목 | OWASP Top 10 (위험 분류) | OWASP ASVS (보안 요구 명세) | OWASP WSTG (보안 시험 지침) |
|:---|:---|:---|:---|
| **문서의 핵심 성격** | **최우선 주의 대상 10대 보안 위험 요약서** | **소프트웨어 보안 아키텍처 요구사항 명세서**| **모의 침투 테스트 및 취약점 진단 가이드** |
| **주요 활용 단계** | **기획 및 전략 수립 (Risk Awareness)** | **아키텍처 설계 및 구현 (Secure Design)** | **QA 테스트 및 배포 전 검증 (Verification)**|
| **상세도 및 형식** | 거시적 10대 범주 (개념 및 사례 설명) | **3단계 레벨, 수백 개 세부 기술 요구사항** | **단계별 공격 시나리오 및 진단 체크리스트** |
| **주요 대상 독자** | 경영진, 개발 총괄, 보안 기획자 | **소프트웨어 개발자, 보안 아키텍트** | **모의 침투 테스터, QA 엔지니어, 보안 진단원**|
| **핵심 기여 가치** | **보안 투자 우선순위 선정 및 공감대 형성**| **보안이 내재화된 안전한 소프트웨어 빌드** | **시스템의 실질적 공격 방어 통제력 실증** |

#### 한줄 요약
- Top 10은 위험 인식(What), ASVS는 설계 구현(How to Build), WSTG는 테스트 검증(How to Test)을 담당한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **체크리스트 증후군(Checklist Syndrome)**: OWASP Top 10의 10개 항목만 단순 체크리스트로 확인하고, 애플리케이션 고유의 비즈니스 로직 결함(예: 결제 금액 변조, 다단계 워크플로 우회)에 대한 위협 모델링과 심층 진단을 누락하는 보안 진단의 한계.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| Top 10 항목만 단순 체크리스트로 형식적 점검하여 **비즈니스 로직 우회 및 API 권한 탈취 사고 발생** | **기획/설계 단계부터 OWASP ASVS 4.0(Level 2) 보안 아키텍처 요구사항 의무 적용** | 겉핥기식 점검 탈피 및 구조적 보안 결함의 Shift-Left 선제 방어 완성 |
| 모의 침투 테스터의 비표준화된 무차별 공격으로 인한 **테스트 환경 장애 및 재현 불가능한 보고서** | **OWASP WSTG 4.2 표준 테스트 케이스 기반의 통제된 침투 시험 절차 준수** 의무화 | 서비스 가용성 영향 0% 유지 및 100% 재현 가능한 고품질 진단 결과 확보 |
| 과거 10년 전 Top 10 룰셋에만 머물러 **최신 클라우드 API 권한 붕괴(BOLA) 및 SSRF 공격 방어 실패** | **최신 OWASP Top 10 및 OWASP API Security Top 10을 전사 보안 표준에 주기적 반영** | 진화하는 최신 클라우드/API 위협에 대한 빈틈없는 선제 방어력 확보 |

#### 한줄 요약
- ASVS로 구조적 설계를 내재화하고, WSTG로 재현 가능한 검증을 수행하며, 최신 표준을 지속 반영한다.

## Ⅶ. 결론

- 웹 애플리케이션의 복잡성과 공격 표면이 급증하는 현대 환경에서 **OWASP Top 10 아키텍처**는 전사 보안 위험 인식과 거버넌스의 핵심 나침반이며, 실무 구현 시 **Top 10 기반 위험 식별**, **ASVS 기반 안전한 설계 및 시큐어 코딩 내재화**, **WSTG 기반 실증적 모의 침투 검증**, **CI/CD 파이프라인 자동화 연동**을 결합하여 결함 없는 소프트웨어 보안 레질리언스를 완성

#### 한줄 요약
- Top 10 위험 식별과 ASVS 설계 규격 및 WSTG 침투 검증을 결합하여 시큐어 SDLC 생태계를 완성한다.
