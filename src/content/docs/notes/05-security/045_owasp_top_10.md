## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **개방형 웹 애플리케이션 보안 프로젝트(Open Worldwide Application Security Project, OWASP)**: 애플리케이션 보안 지침과 시험 도구를 공개하는 비영리 프로젝트이다.
- **OWASP Top 10**: 가장 중요한 웹 애플리케이션 위험 범주 10개를 제시하는 위험 인식 자료이다.

</details>

- 정의/개념: **OWASP Top 10**은 주요 웹 위험을 정리해 조직 간 우선순위 판단을 돕는다.
- 배경/필요성: 개별 취약점 목록만으로는 위험의 상대적 중요도를 공유하기 어렵다.

#### 한줄 요약

- 반복되는 웹 위험을 공통 언어로 묶어 보안 요구와 시험으로 연결한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **위험 인식 자료**: 우선 위험을 공통 언어로 제시하되 검증 표준이나 준수 인증 자체는 아닌 자료이다.
- **주기적 갱신**: 자료와 전문가 검토를 반영해 변화한 웹 공격 위험을 다시 분류하는 활동이다.
- **애플리케이션 보안 검증 표준(Application Security Verification Standard, ASVS)**: 보안 요구사항과 검증 수준을 정의하는 표준이다.
- **웹 보안 시험 지침(Web Security Testing Guide, WSTG)**: 웹 보안 시험 항목과 절차를 제시하는 지침이다.

</details>

- **위험 인식 자료**는 원인과 영향 중심으로 웹 위험을 공통 분류한다.
- 자료와 전문가 검토에 따른 **주기적 갱신**으로 변화한 공격 양상을 반영한다.
- **ASVS**와 **WSTG**를 연결해 추상적인 위험을 요구사항과 시험 절차로 구체화한다.

#### 한줄 요약

- 위험 목록을 ASVS 요구와 WSTG 시험으로 구체화해야 한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **소프트웨어 개발 생명주기(Software Development Life Cycle, SDLC)**: 요구•설계•개발•시험•배포•운영의 전 과정이다.

</details>

```text
OWASP 활용 구조
├─ Top 10 위험 범주: 주요 웹 위험 분류
├─ ASVS 보안 요구: 검증 요구•수준 정의
├─ WSTG 시험 절차: 웹 보안 시험 제공
├─ SDLC 통제: 개발 전 과정에 통제 반영
└─ 운영 근거: 사고•변경 결과로 판단 보완
```

| 구성요소 | 책임 |
|:---|:---|
| Top 10 위험 범주 | 주요 웹 위험의 공통 분류 |
| ASVS 보안 요구 | 위험별 검증 요구•수준 정의 |
| WSTG 시험 절차 | 요구별 웹 보안 시험 제공 |
| SDLC 통제 | 요구•설계•개발•시험에 **SDLC** 통제 반영 |
| 운영 근거 | 사고•변경 결과로 위험 판단 보완 |

#### 한줄 요약

- Top 10 위험을 ASVS 통제와 WSTG 시험에 연결해 수명주기에 반영한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **검증 증거**: 보안 요구의 구현 결과와 설계•코드•동적 시험의 재현 가능한 기록이다.
- **Top 10 위험 범주 매핑**: 서비스 기능과 의존성에 적용되는 OWASP Top 10 위험을 연결하는 단계이다.
- **ASVS 보안 요구 선정**: 위험과 보호 수준에 맞는 ASVS 요구사항을 선택하는 단계이다.
- **보안 통제 구현**: 선정한 요구사항을 설계와 코드의 예방•탐지 통제로 구현하는 단계이다.
- **WSTG 보안 시험**: WSTG 절차에 따라 구현된 통제의 유효성을 확인하는 단계이다.
- **사고•변경 근거 환류**: 운영 중 수집한 사고와 변경 증거를 위험•요구 개선에 반영하는 단계이다.

</details>

```text
서비스 경계•중요도
        |
        v
1. Top 10 위험 범주 매핑
        |
        v
2. ASVS 보안 요구 선정
        |
        v
3. 보안 통제 구현
        |
        v
4. WSTG 보안 시험
        |
        +-- 미충족 -- 통제•요구 보완
        |
        +-- 충족 -- 운영 근거 수집
                           |
                           v
                 5. 사고•변경 근거 환류
```

### 동작 원리

1. **Top 10 위험 범주 매핑**: 기능•의존성별 적용 위험을 식별해 Top 10 위험 범주 매핑을 완성한다.
2. **ASVS 보안 요구 선정**: 위험과 보호 수준에 맞는 요구를 골라 ASVS 보안 요구 선정을 완료한다.
3. **보안 통제 구현**: 설계•코드에 검증 가능한 통제를 반영해 보안 통제 구현 결과를 만든다.
4. **WSTG 보안 시험**: 설계•코드•동적 시험으로 통제를 검증하고 WSTG 보안 시험의 **검증 증거**를 남긴다.
5. **사고•변경 근거 환류**: 운영 증거를 위험•요구 개선에 반영해 사고•변경 근거 환류를 수행한다.

#### 한줄 요약

- 적용 대상과 범위를 정한 뒤 위험별 요구•시험•운영 지표를 연결한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **위험•요구•시험 역할 분리**: Top 10은 위험 인식, ASVS는 요구 정의, WSTG는 시험 절차에 각각 사용하는 선택 원칙이다.

</details>

| OWASP 자료 | 담당 역할 | 활용 산출물 |
|:---|:---|:---|
| **OWASP Top 10** | 주요 웹 위험 인식 | 교육•위험 논의의 공통 범주 |
| **ASVS** | 보안 요구사항•검증 수준 정의 | 설계•개발•검수 요구 기준 |
| **WSTG** | 웹 보안 시험 절차 제공 | 시험 시나리오•점검 절차 |

#### 한줄 요약

- **위험•요구•시험 역할 분리**에 따라 Top 10은 위험 인식, ASVS는 요구, WSTG는 시험에 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **OWASP Top 10:2025**: 2025년에 공개된 OWASP Top 10 웹 애플리케이션 위험 분류판이다.
- **OWASP ASVS 5.0.0**: 애플리케이션 보안 요구사항과 검증 수준을 정리한 ASVS 5.0.0 판이다.
- **OWASP WSTG**: 재현 가능한 웹 보안 시험 시나리오와 절차를 제공하는 OWASP 지침이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 오래된 분류를 쓰면 새 공격 경로의 우선순위 누락 | **OWASP Top 10:2025** 적용 | 최신 웹 위험 범주 반영 |
| Top 10만 점검하면 검증 가능한 통제 요구 부재 | **OWASP ASVS 5.0.0**으로 구체화 | 수준별 보안 요구사항 확보 |
| 자체 시험만 수행하면 범위•재현 절차 불일치 | **OWASP WSTG** 절차 연계 | 일관되고 재현 가능한 검증 수행 |

#### 한줄 요약

- 로그인한 사용자가 거래번호를 바꿔 다른 고객의 내역을 조회하지 못하도록 서버가 요청마다 객체 소유권을 검증한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **OWASP 자료 선택 기준**: 위험 인식에는 Top 10, 요구 정의에는 ASVS, 시험 절차에는 WSTG를 적용하는 판단 기준이다.

</details>

- **OWASP 자료 선택 기준**에 따라 위험 인식은 **Top 10**, 요구 정의는 **ASVS**, 시험 절차는 **WSTG**을 선택한다.

#### 한줄 요약

- Top 10은 체크리스트가 아니라 요구와 시험을 정하는 출발점이다.
