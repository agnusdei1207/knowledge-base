## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CASB (클라우드 접근 보안 브로커 / Cloud Access Security Broker)**: 온프레미스 단말과 멀티 클라우드 SaaS 애플리케이션 사이에 위치하여 중앙 보안 정책을 인라인/API 기반으로 중계 및 집행하는 제어 솔루션
- **SaaS (서비스형 소프트웨어)**: 클라우드 공급자가 운영하는 완성형 소프트웨어 서비스(Salesforce, M365 등) 모델

</details>

- 정의: 사내외 사용자와 멀티 클라우드 SaaS 서비스 간 트래픽을 중계하여 가시성 확보, 데이터 유출 방지(DLP), 위협 탐지, 컴플라이언스 준수를 통합 집행하는 클라우드 보안 제어 체계
- 배경: 기업 내 SaaS 활용 급증에 따른 그림자 IT(Shadow IT) 확산과 민감 데이터의 비인가 외부 공유 및 유출 위험 통제 필요성

#### 한줄 요약

- SaaS 사용에 대한 실시간 트래픽 가시성 확보와 데이터 유출 방지(DLP) 정책을 통합 집행하는 중계 보안 제어 솔루션

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **클라우드 발견 (Cloud Discovery)**: 방화벽 및 보안 웹 게이트웨이(SWG) 로그 분석을 통해 사내에서 사용 중인 수천 개 SaaS의 종류와 위험도를 자동 식별하는 기능
- **그림자 IT (Shadow IT)**: 중앙 보안 부서의 승인 없이 임직원이 임의로 구독 및 사용하는 비인가 클라우드 서비스 및 데이터 자산
- **프록시 (Forward / Reverse Proxy)**: 클라이언트와 SaaS 간 패킷 통로에서 SSL/TLS 트래픽을 복호화하고 실시간 인라인 차단을 수행하는 기술
- **API 연동 (API Connector)**: SaaS 벤더의 REST API를 연계하여 저장된 파일의 공유 상태, 멀웨어 감염, 권한 오설정을 무마찰로 검사하는 기술
- **DLP (데이터 유출 방지 / Data Loss Prevention)**: 개인정보 및 기업 기밀의 클라우드 업로드와 외부 공개 공유를 탐지하여 암호화 및 차단하는 보안 기술

</details>

- **그림자 IT 자동 발견 및 위험 평가**: 네트워크 로그 기반 클라우드 디스커버리를 통해 미인가 SaaS 사용 현황을 가시화하고 위험 점수(Risk Rating) 산출
- **하이브리드 배치 모델 (Proxy + API)**: 실시간 차단을 위한 인라인 프록시(Forward/Reverse)와 저장 데이터 감시용 API 커넥터의 유기적 결합
- **맥락 기반 인라인 DLP 통제**: 사용자 신원, 단말 보안 상태(BYOD vs 관리 단말), 데이터 민감도에 따른 실시간 다운로드 차단, DRM 연동, 화면 캡처 방지 집행

#### 한줄 요약

- 그림자 IT 자동 탐지, 프록시/API 하이브리드 배치, 맥락 기반 DLP 집행을 통한 클라우드 데이터 유출 차단

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **정책 엔진 (Policy Engine)**: 사용자 신원, 기기 무결성, 접속 위치, 데이터 민감도를 대조하여 허용, 차단, 암호화, MFA를 결정하는 중앙 통제 모듈
- **서비스 위험 평가 (Service Risk Rating)**: SaaS 서비스의 보안 인증(SOC 2, ISO 27001), 데이터 암호화 지원 여부, 사고 이력을 바탕으로 산출한 위험도 지표
- **예외 감사 증적 (Exception Audit Log)**: 업무상 불가피하게 허용된 예외 접근에 대해 승인 사유, 기한, 작업 이력을 암호화 보존한 감사 기록

</details>

```text
                     [중앙 정책 엔진 / 위험 평가]
                      /                      \
             [클라우드 발견]              [인라인 프록시 / API 집행]
             (Shadow IT 탐지)             (실시간 DLP / 저장 데이터 감사)
                      \                      /
                     [SaaS 애플리케이션 보호 자산]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **클라우드 발견 엔진** | 방화벽/SWG 로그 수집 및 SaaS 앱 식별, **서비스 위험 평가(Risk Rating)** 산출 | Visibility |
| **중앙 정책 엔진** | IAM 신원, 기기 상태, 접속 맥락을 평가하여 인라인 차단, 암호화, MFA 집행 결정 | Control Core |
| **인라인 프록시** | Forward/Reverse 프록시를 통한 실시간 트래픽 가로채기 및 업로드/다운로드 차단 | Data Plane (Inline) |
| **API 커넥터** | SaaS 백엔드 REST API를 통한 저장 파일 검사, 공개 공유 링크 자동 회수 | Out-of-band |
| **UEBA / 위협 분석** | 사용자 행동 이상 징후(비정상 대량 다운로드) 탐지 및 **예외 감사 증적** 보존 | Threat Protection |

#### 한줄 요약

- 정책 엔진의 맥락 평가에 기반하여 프록시의 실시간 인라인 패킷 차단과 API 커넥터의 저장 데이터 정밀 감시를 병행 집행

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **인라인 검사 (Inline Inspection)**: 프록시 경로를 통해 트래픽을 실시간 복호화하여 패킷 내 데이터 민감도 및 업로드/다운로드를 즉시 제어하는 방식
- **API 비동기 점검 (API Out-of-band Inspection)**: SaaS REST API를 통해 이미 저장된 파일의 외부 공유 상태, 악성코드 감염 여부를 비동기로 점검하는 방식

</details>

```text
[실시간 SaaS 접근 요청]
          │
          ▼
1. 신원 / 기기 상태 / 데이터 민감도 맥락 확인
          │
          ▼
2. 중앙 정책 엔진 보호 조치 결정 (허용, 차단, 암호화, MFA)
          │
          ▼
3. 인라인 프록시 DLP 및 접근 제어 집행
          │
          ▼
[SaaS 서비스 정상 이용]

[SaaS 내 저장 데이터 비동기 점검]
          │
          ▼
4. API 커넥터를 통한 파일 저장 상태 및 공유 링크 조회
          │
          ▼
5. 외부 전체 공개 등 위반 파일 탐지 및 공유 권한 즉시 회수
          │
          ▼
[사후 데이터 위험 격리 완료]
```

### 동작 원리

1. 맥락 분석: 사용자 신원, 단말 무결성(Posture), 접속 IP 및 요청 데이터의 민감도(주민번호 등) 확인
2. 통제 결정: 정의된 정책에 따라 단순 허용, 차단, 실시간 암호화, 추가 MFA 강제 여부 결정
3. 인라인 집행: Forward/Reverse 프록시를 통해 비인가 SaaS 접근 및 기밀 파일 업로드를 실시간 차단
4. API 점검: 백그라운드에서 SaaS API를 호출하여 저장된 파일의 악성코드 감염 및 외부 공개 링크 점검
5. 위반 조치: 비인가 공개 공유 링크 자동 해제, 악성 파일 격리 및 보안 관리자 경보 발송

#### 한줄 요약

- 인라인 프록시 기반의 실시간 트래픽 차단과 API 연동 기반의 저장 데이터 사후 공유 권한 회수 절차 완결

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **TLS 검사 부하 (TLS Inspection Overhead)**: SSL/TLS 대용량 트래픽의 복호화 및 재암호화 처리에 따른 CASB 프록시 인프라의 지연(Latency) 및 연산 병목 현상
- **로그 기반 발견 (Log-based Discovery)**: 방화벽, SWG 로그를 수집하여 사내 SaaS 사용 현황 및 위험도만 수동/자동 분석하는 비간섭 방식

</details>

| CASB 구현 형태 | **로그 기반 발견 (Log-based)** | **Forward Proxy** | **Reverse Proxy** | **API 연동 (Out-of-band)** |
|:---|:---|:---|:---|:---|
| 배치 방식 | 방화벽/SWG 로그 분석 | 사용자 단말 에이전트/PAC 설정 | SaaS DNS CNAME 변경 배치 | SaaS 제공자 REST API 연동 |
| 주요 기능 | 그림자 IT 시각화, 위험도 측정 | 전체 Web/SaaS 실시간 DLP | 인가된 특정 SaaS 실시간 DLP | 저장 파일 검사, 공유 권한 회수 |
| 핵심 장점 | 네트워크 영향 제로, 빠른 도입 | 미인가 SaaS 실시간 차단 가능 | 단말 에이전트 미설치(BYOD) 지원 | 네트워크 지연 zero, 무마찰 |
| 주요 한계 | 실시간 차단 불가능 | 에이전트 설치 필수, **TLS 검사 부하** | 미인가 SaaS 통제 불가 | 실시간 차단 불가(사후 조치) |

#### 한줄 요약

- 실시간 차단을 위한 Forward/Reverse 프록시와 네트워크 지연 없는 저장을 탐지하는 API 방식을 결합한 Hybrid CASB 구축

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/IEC 27017:2015**: 클라우드 서비스 환경의 거버넌스 및 고객/제공자의 보안 통제 요구사항 지침
- **CSA CCM v4.1 (Cloud Controls Matrix)**: 17개 도메인의 197개 통제 항목으로 구성된 글로벌 클라우드 보안 프레임워크

</details>

| 장애 및 위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| SaaS 서비스 위험도 평가 기준 부재 | 정량적 보안성 검토 없이 부서별 임의 SaaS 도입 | **ISO/IEC 27017** 및 **CSA CCM v4.1** 기반 위험 평가 기준 정립 | SaaS 서비스 위험도(Risk Rating) 객관적 산출 및 도입 통제 |
| 단일 프록시 도입 시 성능 저하 및 우회 발생 | SSL 복호화 병목 현상 및 모바일/BYOD 단말 통제 불가 | **Hybrid CASB (Proxy + API)** 복합 아키텍처 구현 | 인라인 실시간 차단과 API 무마찰 검사의 상호보완적 사각지대 제거 |
| 대량 오탐으로 인한 정상 업무 차단 | 과도하게 엄격한 정규식 기반 단일 DLP 정책 적용 | 머신러닝 기반 문서 지문(Fingerprint) 인식 및 점진적 차단 전환 | 오탐 감소 및 사용자 업무 연속성 보장 |

#### 한줄 요약

- ISO 27017 및 CSA CCM 기반 SaaS 위험 평가, Hybrid CASB 배치를 통한 성능과 보안 사각지대 동시 해소

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **집행 사각지대 (Enforcement Blind Spot)**: 미관리 단말(BYOD), 모바일 앱, 비인가 SaaS 접속 시 프록시나 API 통제를 벗어나는 보안 가시성 공백 영역

</details>

- 멀티 클라우드 및 재택근무 환경에서 기업 데이터의 안전한 유통을 보장하기 위해, **로그 기반 발견** 기반 그림자 IT를 가시화하고, **인라인 프록시** 실시간 차단과 **사후 API 연동** 무마찰 감사 체계를 결합하여 **집행 사각지대** 활용 근본적으로 제거하는 하이브리드 CASB 거버넌스 확립 필수

#### 한줄 요약

- 실시간 인라인 프록시와 사후 API 연동을 결합한 하이브리드 CASB 구축을 통한 SaaS 데이터 보호 완성
