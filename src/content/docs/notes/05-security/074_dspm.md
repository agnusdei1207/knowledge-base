## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DSPM (데이터 보안 형상 관리 / Data Security Posture Management)**: 멀티 클라우드 및 온프레미스 저장소의 민감 데이터 위치, 접근 권한, 이동 경로, 보안 위험을 자동 식별하고 지속 교정하는 데이터 중심 보안 통제 기술이다.
- **그림자 데이터 (Shadow Data)**: 중앙 IT/보안 부서의 관리를 벗어나 미인가 클라우드 저장소, DB 백업본, 개발용 S3 등에 방치된 미관리 민감 데이터이다.

</details>

- 정의: 클라우드 인프라 자체를 점검하는 CSPM을 넘어, 데이터의 내용과 이동 흐름을 추적하여 암호화 누락 및 접근 과권한을 차단하는 지향 클라우드 데이터 보호 체계이다.
- 배경: 클라우드 워크로드의 동적 확장 과정에서 개발자가 임의로 복제해 둔 민감 PII 백업본(그림자 데이터)이 대규모 정보 유출의 공격 표면이 되었기 때문이다.

#### 한줄 요약

- 인프라 설정을 넘어 저장 데이터 위치, 민감도 분류, 유효 접근 권한, 복제 계보를 통합 가시화하여 위험을 교정하는 보안 체계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **데이터 분류 (Data Classification)**: RegEx, NLP, ML 알고리즘을 이용해 개인정보, 금융정보, 지적재산권 데이터를 등급별로 자동 태깅하는 식별 활동이다.
- **데이터 계보 (Data Lineage)**: 원천 데이터가 어디서 생성되어 어떤 파이프라인 및 복제본(Snapshot)으로 이동했는지 전체 흐름을 가시화하는 추적 기법이다.
- **SaaS (서비스형 소프트웨어 / Software as a Service)**: M365, Salesforce 등 완제품 애플리케이션 내에 저장되는 비정형 데이터 저장 환경이다.
- **유효 접근 (Effective Access)**: IAM 정책, 그룹 권한, 네트워크 룰을 복합 계산하여 실제 데이터 자산에 도달 가능한 사용자의 실질적 인가 범위이다.

</details>

- **전방위 데이터 발견**: 멀티 클라우드(AWS S3, GCP GCS), 자체 DB, SaaS 내 모든 데이터의 자동 발견 및 식별을 집행한다.
- **계보 및 민감도 융합**: 데이터 분류 기술과 데이터 계보 분석을 결합하여 복제 방치된 민감 데이터의 원천 파악 및 삭제를 유도한다.
- **과권한 식별 및 차단**: IAM 직접 권한과 간접 상속 권한을 복합 분석한 유효 접근 권한을 도출해 과권한(Over-privileged) 위험을 원천 차단한다.

#### 한줄 요약

- 민감 데이터 분류, 데이터 이동 계보 추적 및 유효 접근 권한 계산을 통해 미관리 그림자 데이터의 보안 위험을 제거한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **발견 엔진 (Discovery Engine)**: API 및 비침투 스캔 기반으로 계정 내 모든 정형/비정형 데이터 저장소와 데이터베이스를 탐지하는 모듈이다.
- **분류 엔진 (Classification Engine)**: NLP 및 딥러닝 알고리즘으로 PII, PCI-DSS 대상, 암호화 키 등 민감 데이터 종류와 등급을 자동 판정하는 모듈이다.
- **데이터 소유자 (Data Owner)**: 식별된 데이터 위험에 대해 권한 축소, 암호화, 파기 승인 등 최종 조치 책임을 지는 현업 주체이다.
- **마스킹 (Masking)**: 개인정보 유출 방지를 위해 데이터 원본의 일부 또는 전체를 난수화/별표 처리하는 비식별화 기술이다.

</details>

```text
                         [저장소 연동]
                        /          \
               [발견·분류 엔진]  [접근·계보 분석]
                        \          /
                          [위험 우선순위]
                                |
                       [조치·소유자 연계]
```

| 구성요소 | 주요 책임 및 역할 | 비고 |
|:---|:---|:---|
| **저장소 연동** | 멀티 클라우드 Storage, RDBMS, NoSQL, SaaS API 커넥터 연동 | Connectors |
| **발견 / 분류 엔진** | 미관리 데이터베이스 스캔 및 딥러닝 기반 데이터 민감도 자동 분류 | Discovery |
| **접근 / 계보 분석** | IAM 복합 분석으로 유효 접근 권한 산출 및 스냅샷 복제본 간 데이터 계보 매핑 | Lineage |
| **위험 우선순위** | 민감도, 인터넷 노출 여부, 과권한 상태, 미암호화 여부를 결합한 위험 점수 산출 | Prioritization |
| **조치 / 소유자 연계** | 데이터 소유자 지정, 권한 차단, **마스킹**, 격리 및 파기 조치 집행 | Remediation |

#### 한줄 요약

- 발견 엔진과 계보 분석 모듈이 데이터 실체를 파악하고, 산출된 위험 점수에 따라 데이터 소유자가 즉각적인 보호 조치를 집행한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비침투형 발견 (Non-intrusive Discovery)**: DB 런타임 성능 저하 없이 Read-Only 메타데이터 및 스냅샷 복제본을 활용해 분석 스캔하는 기법이다.
- **잔여 노출 (Residual Exposure)**: 보안 조치 실행 후에도 남아있는 잠재적 데이터 노출 및 취약성 잔여 위험 수준이다.

</details>

```text
[멀티 클라우드 데이터 저장소]
      |
      `-- 내용·권한·암호화 정보 제공
                  |
                  v
[DSPM 중앙 분석 플랫폼]
                  |
                  v
1. 데이터 발견 및 민감도 분류
                  |
                  v
2. 유효 접근 통제권 및 데이터 계보 매핑
                  |
                  v
3. 데이터 위험 우선순위 산출
                  |
                  `-- 데이터 노출 위험 근거 도출
                              |
                              v
[데이터 소유자 및 보안 관리자]
                              |
                              v
4. 보호 조치 결정 및 소유 책임 확정
                              |
                              `-- 권한 회수·마스킹·파기 승인
                                          |
                                          v
[자동화 조치 시스템]
                                          |
                                          v
5. 원천 보호 조치 집행 및 잔여 노출 검증
                                          |
                                          v
[그림자 데이터 위험 제거 완료]
```

### 동작 원리

1. 발견/분류: 멀티 클라우드 전역의 방치된 저장소를 탐지하고 PII 등급을 분류한다.
2. 접근/계보 매핑: 해당 데이터에 대한 실제 인가자와 복제 파이프라인 지도를 구성한다.
3. 우선순위 산출: 인터넷 노출도, 미암호화 여부, 민감도를 결합해 위험을 평가한다.
4. 소유자 확정: 조치 대상을 현업 소유자에게 할당하고 마스킹/파기 방안을 수립한다.
5. 조치 및 검증: 보안 통제를 집행하고 잔여 노출을 재검증한다.

#### 한줄 요약

- 비침투 스캔 발견, 유효 접근 및 계보 계산, 위험 우선순위 산정, 소유자 조치 집행 및 잔여 검증으로 순환 관리한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **CSPM (클라우드 보안 형상 관리 / Cloud Security Posture Management)**: 클라우드 인프라 자원의 설정 오류 및 보안 통제 컴플라이언스를 스캐닝하는 보안 솔루션이다.
- **DLP (데이터 유출 방지 / Data Loss Prevention)**: 네트워크 트래픽이나 엔드포인트 상에서 파일의 외부 반출을 실시간 검사 및 차단하는 솔루션이다.

</details>

| 데이터 보안 체계 | **DSPM (데이터 중심)** | **CSPM (인프라 설정 중심)** | **DLP (전송 트래픽 중심)** |
|:---|:---|:---|:---|
| 핵심 통제 대상 | **저장 데이터 실체**, 민감도, 복제 계보 | 클라우드 방화벽, S3 퍼블릭 노출 등 인프라 설정 | 이메일, USB, 웹 업로드 등 데이터 전송 트래픽 |
| 강점 | 미관리된 그림자 데이터의 정밀 식별 및 내용 기반 위협 분류 우수 | 인프라 전반의 광범위한 보안 설정 및 컴플라이언스 준수 점검 가능 | 전송 단계의 명확한 정책 기반 실시간 유출 차단 가능 |
| 장단점 및 한계 | 인프라 오설정 방어는 한계 | **저장된 데이터 내용 및 PII 존재 여부 식별 불가** | **방치된 클라우드 스토리지의 그림자 데이터 발견 불가** |

#### 한줄 요약

- 인프라 오설정에 치중한 CSPM과 전송 차단 중심의 DLP 한계를 극복하고, DSPM은 저장 데이터 실체와 유효 접근 통제 팩트에 집중한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/IEC 27002 통제 5.12**: 정보 자산의 분류, 식별, 취급 등급 부여에 관한 국제 정보보호 표준 지침이다.
- **NIST SP 800-122**: 개인식별정보(PII) 기밀성 보존 및 기밀성 유출 영향 평가 가이드라인 표준이다.

</details>

| 장애/위험 요소 | 원인 분석 | 실무 대책 및 해결방안 | 기대 효과 |
|:---|:---|:---|:---|
| **부서별 데이터 분류 체계 파편화** | 전사 공통의 민감도(Confidential, Internal 등) 기준 부재 | **ISO/IEC 27002 통제 5.12** 준용 기반 체계 수립 | 전사 멀티 클라우드 자산에 대한 통일된 분류 스키마 정합성 확보 |
| **운영 DB 대상 침투 스캔 시 부하 발생** | 정규표현식 및 ML 스캔 모듈의 클라우드 컴퓨팅 자원 과다 소모 | 스냅샷 기반의 **비침투형 스캔(Out-of-band)** 아키텍처 적용 | 운영 서버/DB 성능 저하 제로 보장 및 지속적 가시성 확보 |
| **방대한 탐지로 인한 보안팀 업무 마비** | 모든 민감 데이터 존재 알람을 일괄 경보 처리 | **NIST SP 800-122** 연계 **노출 위험 우선순위화** 적용 | 퍼블릭 노출된 PII 데이터에만 보안 역량 집중 및 마스킹 강제 |

#### 한줄 요약

- ISO 27002 및 NIST 표준을 바탕으로 분류 체계를 정립하고, 비침투 스캔 아키텍처로 성능 저하 없이 PII 노출을 우선 차단한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **데이터 위험 감소 성과 (Data Risk Reduction Performance)**: 단순 인프라 설정 오류 탐지를 넘어 실질적인 민감 그림자 데이터 방치 건수 및 과권한 유출 경로 감소를 입증하는 실적 지표이다.

</details>

- 멀티 클라우드 환경에서 개발 속도를 저해하지 않으면서 그림자 데이터 유출을 막기 위해, 저장 데이터 실체는 **DSPM**, 인프라 형상 제어는 **CSPM**, 트래픽 반출 차단은 **DLP**로 다층 배치하여 실질적인 **데이터 위험 감소 성과**를 입증하는 데이터 중심 보안 거버넌스 확립 필수이다.

#### 한줄 요약

- 클라우드 저장은 **DSPM**, 인프라 설정은 **CSPM**, 네트워크 전송은 DLP를 입체 적용해 전주기 데이터 보안을 완성한다.
