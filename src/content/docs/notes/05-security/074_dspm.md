## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **DSPM(Data Security Posture Management, 데이터 보안 형상 관리 / Gartner)**: 멀티 클라우드(IaaS, PaaS, SaaS) 및 온프레미스 스토리지, RDBMS, NoSQL 전역에 저장된 데이터 자산의 위치, 민감도 등급(PII, 금융, 지적재산), 복제 계보(Data Lineage), 유효 접근 권한(Effective Access), 암호화 여부를 비침투적으로 자동 발견·분류하고 보안 위험을 지속적으로 교정하는 데이터 중심 보안 거버넌스 기술.
- **그림자 데이터 및 미관리 백업 방치(Shadow Data & Orphan Backup Defect)**: 개발 및 테스트 과정에서 개발자가 프로덕션 DB를 개발용 S3 버킷이나 비인가 스토리지로 무단 복제해 둔 후 방치하여, 인프라 방화벽 점검(CSPM)만으로는 탐지할 수 없는 대규모 개인정보 유출 공격 표면이 형성되는 결함.

</details>

- 정의/개념: 인프라 설정만 점검하는 CSPM의 한계를 넘어, 데이터 실체 발견(Discovery) $\rightarrow$ NLP/ML 기반 민감도 자동 분류 $\rightarrow$ 복제 계보(Lineage) 및 유효 권한 매핑 $\rightarrow$ 위험 우선순위화 $\rightarrow$ 비침투적 스냅샷 기반 보안 조치(마스킹/암호화/파기) 를 집행하는 데이터 중심 클라우드 보안 아키텍처
- 배경/필요성: 멀티 클라우드 및 SaaS 환경에서 개발·테스트 목적으로 복제된 후 방치된 그림자 데이터(Shadow Data), 미인가 S3 백업본, 데이터베이스 복제본이 급증함에 따라, 기존의 인프라 설정 점검(CSPM)만으로는 스토리지 내부의 실제 데이터 민감도(PII/금융 정보)와 유효 접근 권한(Effective Access)을 파악하지 못해 대규모 유출 사고로 이어지는 한계가 존재함에 따라, 프로덕션 성능 부하 없는 비침투적 스냅샷 스캔을 기반으로 데이터 실체 발견, NLP/ML 기반 민감도 자동 분류, 복제 계보(Lineage) 추적 및 위험 우선순위화를 집행하는 **DSPM**(Data Security Posture Management)을 도입하여 전사 멀티 클라우드 데이터 자산의 100% 가시성 확보, 미관리 그림자 데이터의 선제적 파기 및 데이터 중심(Data-Centric) 제로 트러스트 보안 거버넌스를 달성할 필요

#### 한줄 요약
- DSPM은 인프라가 아니라 데이터를 기준으로 위험을 세는 도구이므로, 설정이 같더라도 그 안에 무엇이 담겼는지에 따라 위험 등급이 갈린다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **유효 접근 권한(Effective Access Analysis)**: 단순 IAM 역할뿐만 아니라 그룹 정책, 서비스 제어 정책(SCP), 버킷 ACL, 네트워크 VPC 엔드포인트 룰을 복합 시뮬레이션하여 특정 주체가 해당 데이터에 실질적으로 도달할 수 있는 최종 권한을 도출하는 기술.
- **데이터 계보(Data Lineage Tracking)**: 원천 데이터베이스에서 생성된 데이터가 어떤 ETL 파이프라인, 스냅샷, 복제본을 거쳐 다른 계정이나 버킷으로 이동했는지 전체 라이프사이클 계보를 역추적하는 기술.

</details>

- 내용 중심의 데이터 인텔리전스 (Data-Centric Intelligence): 버킷 이름이나 테이블 스키마가 아닌 실제 데이터 페이로드를 NLP/머신러닝으로 분석하여 정밀 분류
- 비침투적 아웃오브밴드 스캔 (Non-Intrusive Snapshot Scanning): 운영 중인 프로덕션 DB나 인스턴스에 에이전트를 설치하지 않고, 스토리지 스냅샷을 복제하여 격리된 환경에서 스캔함으로써 운영 성능 영향(Latency) 0% 달성
- 과다 권한 및 데이터 노출 경로 차단: 민감 PII가 저장된 스토리지에 대해 불필요한 퍼블릭 접근 권한이나 과도한 개발자 접근 권한을 즉각 식별

#### 한줄 요약
- 스냅샷을 떠서 격리 환경에서 읽는 방식은 운영 부하를 0으로 만드는 대신 스캔 이후의 변경을 보지 못하므로, 가시성은 언제나 스냅샷 주기만큼 과거의 것이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **DSPM 4대 핵심 아키텍처 계층**:
  1. **Cloud Connector Layer**: AWS, Azure, GCP, Snowflake, SaaS API를 통한 스토리지 인벤토리 수집.
  2. **Data Classification Engine**: 딥러닝/정규식 기반 PII, 소스코드, 암호화 키 식별.
  3. **Effective Access & Lineage Engine**: IAM 정책과 네트워크 토폴로지를 결합한 접근 가능성 시뮬레이션.
  4. **Remediation & Governance Layer**: 데이터 소유자 매핑, 암호화 강제, 불필요 데이터 자동 파기.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 멀티 클라우드 데이터 저장소 (AWS S3, RDS, DynamoDB, Snowflake) ]  │
│  └─ [ 읽기 전용 IAM 역할(Read-Only Role) 연동 ➔ EBS/S3 스냅샷 생성 ]   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (비침투적 비동기 스냅샷 복제)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. DSPM 격리 스캔 파이프라인 (Isolated Out-of-band Scanning Engine) ] │
│  ├─ 데이터 발견: 정형/비정형 데이터베이스 및 미관리 S3 버킷 전수 인벤토리│
│  ├─ NLP/ML 자동 분류: 주민번호, 카드번호, API 키, 여권번호 식별         │
│  └─ 데이터 계보(Lineage): "운영 DB ➔ 개발용 S3 복제본 ➔ 분석용 버킷" 추적 │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (분류 결과 및 IAM 메타데이터 전송)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 위험 우선순위화 및 거버넌스 엔진 (Risk Prioritization Engine) ]    │
│  ├─ 위험 스코어링: [민감 PII 존재 + 인터넷 퍼블릭 오픈 + 미암호화]     │
│  ├─ 유효 권한 분석: 실제 해당 데이터를 읽을 수 있는 IAM 주체 10명 식별   │
│  └─ [ 데이터 소유자에게 Jira 티켓 자동 발행 ➔ 불필요 스냅샷 즉시 삭제 ]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 멀티 클라우드 저장소의 스냅샷이 DSPM 격리 엔진에서 비침투적으로 스캔·분류된 후, 위험 스코어링을 거쳐 소유자 조치로 이어지는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| 클라우드 커넥터 | 멀티 클라우드(AWS, GCP, Azure) API를 연동하여 정형/비정형 저장소 자산 수집 | Connectors |
| 비침투 스캔 엔진 | 운영 서버 부하 없이 스냅샷 볼륨을 마운트하여 백그라운드에서 파일 내용 분석 | Out-of-band |
| 데이터 분류기 (ML) | NLP 및 패턴 인식을 통해 PII, PCI-DSS, GDPR 대상 민감 데이터를 4단계 등급 분류 | Classification |
| 유효 접근 분석기 | IAM 정책과 네트워크 라우팅을 교차 분석하여 실제 데이터 도달 가능 주체 도출 | Effective Access|
| 조치 및 거버넌스 모듈 | 데이터 소유자 매핑, 비인가 공유 차단, 미사용 그림자 데이터 파기 워크플로우 집행 | Remediation |

#### 한줄 요약
- 분류기가 내용을 알아내더라도 유효 접근 분석이 없으면 순위를 매길 수 없으므로, DSPM의 판단력은 민감도와 도달 가능성을 겹쳐 보는 지점에서 생긴다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **DSPM 데이터 위험 탐지 및 교정 5단계 수명주기**:
  1. 클라우드 계정 연동 및 저장소 인벤토리 수집
  2. 비침투 스냅샷 기반 데이터 발견 및 NLP 민감도 분류
  3. 데이터 계보(Lineage) 및 실질적 유효 접근 권한 계산
  4. 다차원 위험도(민감도 + 노출도 + 권한) 스코어링
  5. 소유자 지정, 과권한 회수 및 방치된 그림자 데이터 자동 파기

</details>

```text
1. [스토리지 자산 수집] 클라우드 API를 통해 전사 AWS S3, RDS, EBS 볼륨 인벤토리 자동 추출
            │
            ▼
2. [비침투 스냅샷 스캔 및 분류]
    ├─ 운영 DB 부하 방지를 위해 스토리지 볼륨 스냅샷을 생성하여 DSPM 계정에서 마운트
    └─ NLP 머신러닝 엔진이 텍스트를 파싱하여 "고객 주민번호 50만 건 포함(Confidential)" 태깅
            │
            ▼
3. [계보 및 유효 접근성 매핑]
    ├─ 계보 추적: 3개월 전 프로덕션 DB에서 개발 테스트용으로 복제된 백업본(그림자 데이터) 확인
    └─ 유효 접근: 해당 개발 버킷이 퍼블릭(`AllUsers:READ`)으로 개방되어 있음을 시뮬레이션
            │
            ▼
4. [위험 우선순위 판정] [치명적 민감 PII + 인터넷 퍼블릭 노출 + 방치된 백업] ➔ 최고 위험(Critical) 지정
            │
            ▼
5. [데이터 거버넌스 조치 집행]
    ├─ 데이터 소유자(해당 개발팀장)에게 보안 경보 및 조치 요구 전달
    └─ 버킷 퍼블릭 차단(Private 전환) 및 30일 경과 미사용 백업본 즉시 자동 파기(Delete)
```

1. 스토리지 자산 수집: 클라우드 저장소 인벤토리 생성
2. 비침투 스냅샷 스캔 및 분류: 민감 데이터 식별
3. 계보 및 유효 접근성 매핑: 복제·도달 경로 계산
4. 위험 우선순위 판정: 민감도·노출도·권한 결합
5. 데이터 거버넌스 조치 집행: 과권한 회수·백업 파기

#### 한줄 요약
- 같은 민감 데이터라도 퍼블릭 노출과 방치가 겹칠 때만 최고 위험으로 갈리므로, 스코어링 단계가 수억 건의 저장 사실을 조치 가능한 소수로 줄이는 지점이 된다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **데이터 및 클라우드 보안 3대 도구 비교**: DSPM(데이터 형상 관리), CSPM(인프라 형상 관리), DLP(전송 유출 방지)의 비교.

</details>

| 비교 항목 | 데이터 보안 형상 관리 (DSPM) | 클라우드 보안 형상 관리 (CSPM) | 데이터 유출 방지 (DLP) |
|:---|:---|:---|:---|
| 핵심 통제 대상 | 저장된 데이터 실체, 민감도, 계보 | 클라우드 인프라 설정, 방화벽, IAM | 네트워크 전송 패킷, 엔드포인트 반출 |
| 통제 시점 | 저장 상태 (Data-at-Rest) | 설정 배포 및 런타임 인프라 형상 | 전송 상태 (Data-in-Transit) |
| 데이터 내용 인지 | 완벽 지원 (NLP/ML 기반 PII 식별) | 전혀 불가 (인프라 메타데이터만 확인)| 패턴/정규식 기반 텍스트 검사 |
| 주요 해결 과제 | 방치된 그림자 데이터 및 백업본 식별| S3 퍼블릭 오픈, 포트 개방 오설정 | 이메일/웹을 통한 기밀 파일 외부 유출 |
| 상호보완적 역할 | 데이터 자산의 위험도 기준 제공 | 인프라 보안 기본 베이스라인 확립 | 실시간 전송 차단 집행 |

#### 한줄 요약
- CSPM은 인프라 설정, DLP는 네트워크 전송 차단, DSPM은 저장된 데이터 내용과 복제 계보를 통제한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ISO/IEC 27002 통제 5.12 & NIST SP 800-122**: 조직의 데이터 분류 스키마 정립과 개인식별정보(PII)의 기밀성 보존을 위한 국제 표준 가이드라인.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 부서별로 데이터 분류 기준이 달라 전사 멀티 클라우드에 흩어진 데이터 자산의 통합 민감도 식별 실패 | **ISO**/IEC 27002 통제 5.12 및 NIST SP 800-122 기반의 전사 통일된 4단계 데이터 분류 체계 수립 및 NLP 매핑 | 이종 클라우드 및 SaaS 전역에 걸친 일관된 데이터 민감도 거버넌스 100% 확립 |
| 방대한 프로덕션 데이터베이스를 실시간 전수 스캔하다가 DB 서버의 CPU/IOPS가 고갈되어 핵심 서비스 응답 지연 장애 | 스토리지 볼륨 스냅샷을 복제하여 격리된 분석 환경에서 스캔하는 비침투형 아웃오브밴드(Out-of-band) 아키텍처 적용 | 프로덕션 DB 성능 저하 0% 유지 및 24x365 안전한 지속적 데이터 가시성 확보 |
| 수억 건의 단순 개인정보 저장 알람이 쏟아져 실제 위험한 퍼블릭 노출 데이터를 놓치는 보안팀 경보 피로 발생 | 민감도, 인터넷 노출 여부, 미암호화 상태, IAM 과권한을 결합한 데이터 위험 우선순위화(Contextual Prioritization) | 허위 경보 95% 이상 필터링 및 실제 유출 위험 데이터에 보안 조치 역량 집중 |

#### 한줄 요약
- 세 대책은 분류 기준이 흔들리면 함께 무너지므로, 도구 도입보다 전사 공통 민감도 등급 체계를 먼저 세우는 순서가 성패를 가른다.

## Ⅶ. 결론

- 인프라 중심의 보안 통제를 넘어 실제 저장된 데이터의 내용과 민감도를 기준으로 클라우드 전역의 보안 태세를 지속 관리하는 현대 클라우드 데이터 거버넌스 및 CNAPP/DDR(Data Detection and Response) 통합의 핵심 기저 프레임워크로 확고히 자리 잡았으며, 생성형 AI 학습 데이터 보호 및 비정형 데이터 정밀 분류로 진화하는 가운데, 실무 DSPM 구축 시에는 프로덕션 DB 부하 0%를 보장하는 비침투적 아웃오브밴드(Out-of-band) 스냅샷 스캔 파이프라인 구축, NLP 기반의 PII/PCI-DSS 민감도 4단계 자동 분류 체계 수립, IAM 정책과 네트워크 경로를 시뮬레이션한 **유효 접근 권한**(Effective Access) 분석, 방치된 미사용 그림자 데이터의 자동 격리 및 즉각 파기 워크플로우를 결합하여 완벽한 데이터 자산 보안 무결성을 완성

#### 한줄 요약
- 그림자 데이터는 지우는 것이 가장 값싼 조치이므로, 권한을 조이기 전에 남겨 둘 이유가 없는 사본부터 파기하는 것이 조치의 우선순위가 된다.
