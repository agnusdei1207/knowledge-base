## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **데이터 보안 형상 관리(Data Security Posture Management, DSPM)**: 저장 데이터의 민감도·위치·접근·복제·노출을 지속적으로 자동 탐지하고 평가하여 클라우드 및 온프레미스 상의 데이터 위험을 식별 및 제거하는 통제 체계이다.
- **그림자 데이터(Shadow Data)**: 중앙 보안·거버넌스 부서의 관리가 미치지 못하는 상태에서 비공식적으로 생성, 복제, 보관되어 보안 노출을 야기하는 데이터 집합이다.

</details>

- 정의/개념: **DSPM**은 멀티 클라우드 및 온프레미스 환경에 흩어진 데이터 저장소를 자동 탐지하여 저장 데이터의 민감도·위치·유효 접근 권한·복제 계보를 지속 분석하는 데이터 중심 보안 통제 기술이다.
- 배경/필요성: 인프라 구성 중심의 보안만으로는 통제되지 않는 **그림자 데이터(Shadow Data)** 생성을 감지하지 못해, 과잉 권한 부여와 인지하지 못한 민감 데이터 복제 확산으로 인한 정보 유출 사고 위험이 급증함에 따라 필수적으로 요구된다.

#### 한줄 요약

- DSPM은 단순 인프라 설정을 넘어 저장소 내부의 민감 데이터 식별, 유효 접근 권한, 데이터 이동 계보를 통합 분석하는 데이터 중심 형상 관리 체계이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **데이터 분류(Data Classification)**: 데이터의 민감도와 중요도 및 규제 요건에 따라 보호 등급을 자동으로 체계화하는 식별 활동이다.
- **데이터 계보(Data Lineage)**: 데이터의 생성, 변환, 복제, 이동 경로를 시각화하여 원천 데이터부터 최종 복제본까지의 흐름을 추적하는 기술이다.
- **서비스형 소프트웨어(Software as a Service, SaaS)**: 클라우드 공급자가 소프트웨어 애플리케이션을 인터넷을 통해 서비스 형태로 제공하는 모델이다.
- **유효 접근(Effective Access)**: 직접 부여된 권한뿐만 아니라 IAM 역할, 그룹 상속, 네트워크 노출 설정 등이 종합된 실질적인 데이터 접근 및 조회 가능 범위이다.

</details>

- 정형·비정형·**SaaS** 저장소에서 데이터를 자동 발견하고 식별한다.
- **데이터 분류(Data Classification)**와 **데이터 계보(Data Lineage)** 분석을 연결하여 문맥 기반의 민감도 판단과 이동 경로 추적을 수행한다.
- **유효 접근(Effective Access)** 권한과 실제 암호화/보호 상태를 종합 평가하여 실질적인 유출 위협의 위험 우선순위를 산출한다.

#### 한줄 요약

- 설정 오류가 동일하더라도 단순 일반 파일보다 유효 접근 권한이 과도하게 설정된 고객 민감 데이터 복제 저장소를 우선 격리·조치하는 실질적 위험 기반 대응 체계이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **발견 엔진(Discovery Engine)**: 멀티 클라우드 저장소 및 DB 내에 존재하는 데이터 자산 위치를 자동 검출하는 모듈이다.
- **분류 엔진(Classification Engine)**: 자연어 처리 및 머신러닝 패턴을 활용해 저장 데이터의 민감도와 보호 등급을 자동 판정하는 모듈이다.
- **데이터 소유자(Data Owner)**: 정보 자산의 분류, 접근 권한 승인, 보존 및 파기 조치에 대한 궁극적인 책임을 지는 주체이다.
- **마스킹(Masking)**: 개인정보 등 민감 데이터의 일부 또는 전체를 무작위 문자나 별표로 대체하여 비식별화하는 보호 기법이다.

</details>

```text
                         [저장소 연동]
                        /          \
               [발견•분류 엔진]  [접근•계보 분석]
                        \          /
                          [위험 우선순위]
                                |
                       [조치•소유자 연계]
```

선의 의미: 저장소 연동을 기반으로 데이터 발견·분류와 접근·계보 분석을 결합하고, 위험 우선순위 및 조치·소유자 책임을 연결한 정적 DSPM 구조를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 저장소 연동 | 저장소·소유자·복제본 연결 |
| 발견·분류 엔진 | **발견 엔진(Discovery Engine)**·**분류 엔진(Classification Engine)**이 위치·민감도 식별 |
| 접근·계보 분석 | 유효 권한과 이동 경로 계산 |
| 위험 우선순위 | 노출·민감도·보호 상태 결합 |
| 조치·소유자 연계 | **데이터 소유자(Data Owner)**가 권한·**마스킹(Masking)**·삭제 승인 |

#### 한줄 요약

- 데이터 저장소를 정밀 수집·분석하여 민감 데이터 위치와 유효 접근 권한 및 복제 경로를 연계 파악하는 탐지·분석 구조이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **비침투형 발견(Non-intrusive Discovery)**: 데이터베이스 운영 성능에 영향을 주지 않도록 스냅샷이나 읽기 전용 메타데이터 분석 방식을 활용하는 스캔 방식이다.
- **잔여 노출(Residual Exposure)**: 보안 조치 실행 후에도 기술적 한계나 설정 유예로 인해 계속해서 잠재되어 있는 데이터 노출 위험 수준이다.
- **데이터 발견•민감도 분류(Data Discovery & Sensitivity Classification)**: 저장소 내 데이터 존재를 확인하고 민감도를 자동 분류하는 단계이다.
- **유효 접근•데이터 계보 계산(Effective Access & Data Lineage Calculation)**: 실제 접근 가능 사용자와 데이터 복제 이동 경로를 추적 산출하는 단계이다.
- **데이터 위험 우선순위화(Data Risk Prioritization)**: 데이터 중요도, 접근 권한, 노출 정도를 조합하여 조치 순위를 산정하는 단계이다.
- **보호 조치•소유 책임 확정(Remediation & Ownership Assignment)**: 해당 데이터의 관리 책임자를 지정하고 권한 조정 또는 파기 정책을 결정하는 단계이다.
- **보호 조치 적용(Remediation Execution)**: 확정된 보안 통제를 자동 또는 수동으로 실행하고 이행 결과를 검증하는 단계이다.

</details>

```text
[데이터 저장소]
      |
      `-- 내용•권한•암호화 정보
                  |
                  v
[DSPM]
      |
      v
1. 데이터 발견•민감도 분류
      |
      v
2. 유효 접근•데이터 계보 계산
      |
      v
3. 데이터 위험 우선순위화
      |
      `-- 데이터 위험 근거
                  |
                  v
[데이터 소유자]
      |
      v
4. 보호 조치•소유 책임 확정
      |
      `-- 권한•마스킹•삭제 지시
                  |
                  v
[조치 시스템]
      |
      v
5. 보호 조치 적용
      |
      `-- 조치 적용 결과
                  |
                  v
[DSPM 잔여 노출 검증]
```

### 동작 원리

1. **데이터 발견·민감도 분류(Data Discovery & Sensitivity Classification)**: 비침투형 스캔 방식을 통해 데이터 저장소를 자동 탐지하고 민감도를 분류한다.
2. **유효 접근·데이터 계보 계산(Effective Access & Data Lineage Calculation)**: 복합 권한과 데이터 복제·이동 경로를 결합하여 유효 접근자와 데이터 계보를 산출한다.
3. **데이터 위험 우선순위화(Data Risk Prioritization)**: 민감도, 유효 접근성, 암호화 적용 여부 등을 결합하여 정밀한 데이터 위험 우선순위를 지정한다.
4. **보호 조치·소유 책임 확정(Remediation & Ownership Assignment)**: 해당 자산의 데이터 소유자를 명확히 식별하고 적절한 보호 통제(권한 축소, 마스킹, 파기 등) 방식을 결정한다.
5. **보호 조치 적용(Remediation Execution)**: 지정된 보안 통제를 실행하고 재스캔을 통해 잔여 노출 수준을 상시 검증한다.

#### 한줄 요약

- 비침투 방식으로 탐지 및 위험 우선순위를 도출하고 담당자 승인 기반의 즉각적 보호 통제 및 재검증을 수행하는 순환적 운영 라이프사이클 체계이다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **클라우드 보안 형상 관리(Cloud Security Posture Management, CSPM)**: 클라우드 인프라의 설정 오류, 규정 미준수, 잘못된 IAM 통제 등을 지속 점검하는 체계이다.
- **데이터 유출 방지(Data Loss Prevention, DLP)**: 네트워크, 엔드포인트 등에서 민감정보의 외부 유출 및 전송을 실시간 탐지하고 차단하는 보안 솔루션이다.

</details>

| 데이터 보안 유형 | DSPM | CSPM | DLP |
|:---|:---|:---|:---|
| 적용 기준 | 민감 데이터의 위치·노출 파악 | 안전한 클라우드 구성 | 실시간 반출 탐지·차단 |
| 핵심 특징 | **DSPM**의 저장 데이터·접근 분석 | **CSPM**의 클라우드 설정 평가 | **DLP**의 사용·이동 통제 |
| 한계 | 분류 오탐·스캔 공백 | 데이터 내용 미파악 | 미등록 저장 데이터 누락 |

#### 한줄 요약

- CSPM이 인프라 설정 오류를 점검하고 DLP가 데이터 유출을 막는다면, DSPM은 인프라 내부 데이터 내용과 실질적 접근 위험 파악에 집중하는 차별성을 갖는다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **ISO/IEC 27002 통제 5.12(ISO/IEC 27002 Control 5.12)**: 정보의 가치와 법적/업무적 보호 요구사항에 맞춰 정보를 식별하고 분류하도록 명시하는 통제항목이다.
- **NIST SP 800-122(NIST SP 800-122)**: 개인식별정보(PII)의 기밀성을 보존하고 유출 영향을 평가하여 적절한 보호 통제를 설정하기 위한 가이드라인이다.
- **개인 식별 정보(Personally Identifiable Information, PII)**: 다른 정보와 결합하여 특정 개인을 식별할 수 있는 모든 형태의 데이터이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 정보 분류 기준 불일치 | **ISO/IEC 27002 통제 5.12(ISO/IEC 27002 Control 5.12)** 적용 | 민감도·보호 등급 일관화 |
| 개인식별정보 보호 누락 | **NIST SP 800-122(NIST SP 800-122)** 연계 | **PII(Personally Identifiable Information)** 영향 기반 보호 조치 선정 |
| 스캔 공백·과잉 권한 | 자산 대조·최소 읽기·재스캔 | 그림자 데이터와 잔여 노출 축소 |

#### 한줄 요약

- 미관리 클라우드 저장소 내 방치된 민감 데이터와 과도한 권한을 탐지하여 소유자 지정 및 권한 축소/삭제 조치를 연계 수행하는 통제 방안이다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **데이터 위험 감소 성과(Data Risk Reduction Performance)**: 단순히 단순 탐지 건수에 그치지 않고 실제 노출된 민감 데이터와 과잉 권한 경로를 차단 및 제거한 실질적 보안 개선 결과이다.

</details>

- **데이터 위험 감소 성과(Data Risk Reduction Performance)**를 지속 측정하며 저장 데이터·실제 접근은 **DSPM**, 자원 설정은 **CSPM**, 실시간 반출은 **DLP**를 상호 보완적으로 연계 적용한다.

#### 한줄 요약

- 저장 데이터 위치 탐지와 유효 접근성·데이터 계보 분석을 결합하여 그림자 데이터 및 과잉 접근 위험을 근본적으로 제거하는 데이터 보안 형상 관리 체계 구축.
