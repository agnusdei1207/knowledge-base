## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **데이터 보안 형상 관리(Data Security Posture Management, DSPM)**: 멀티 클라우드 및 온프레미스 저장소의 민감 데이터 위치, 접근 권한, 이동 경로, 보안 위험을 자동 식별하고 지속 교정하는 데이터 중심 보안 통제 기술이다.
- **그림자 데이터(Shadow Data)**: 중앙 IT/보안 부서의 관리를 벗어나 미인가 클라우드 저장소, DB 백업본, 개발용 S3 등에 방치된 미관리 민감 데이터이다.

</details>

- 정의/개념: **DSPM**은 데이터 중심 보안 관점에서 정형/비정형 저장소 내 데이터 발견(Discovery), 민감도 분류(Classification), 유효 접근 권한 분석(Effective Access), 데이터 계보 추적(Data Lineage)을 자동화하는 형상 관리 체계이다.
- 배경/필요성: 인프라 설정 중심의 CSPM 한계를 넘어, 과도하게 복사•방치되는 **그림자 데이터**와 민감 개인정보(PII) 유출 위험을 데이터 실체 단위로 정밀 통제하기 위함이다.

#### 한줄 요약

- 인프라 설정을 넘어 저장 데이터 위치, 민감도 분류, 유효 접근 권한, 복제 계보를 통합 가시화하여 위험을 교정하는 보안 체계이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **데이터 분류(Data Classification)**: RegEx, NLP, ML 알고리즘을 이용해 개인정보, 금융정보, 지적재산권 데이터를 등급별 자동 태깅하는 식별 활동이다.
- **데이터 계보(Data Lineage)**: 원천 데이터가 어디서 생성되어 어떤 파이프라인 및 복제본(Snapshot/Backup)으로 이동했는지 전체 흐름을 가시화하는 추적 기법이다.
- **서비스형 소프트웨어(Software as a Service, SaaS)**: M365, Salesforce 등 완제품 애플리케이션 내에 저장되는 비정형 데이터 저장 환경이다.
- **유효 접근(Effective Access)**: IAM 정책, 그룹 권한, 네트워크 룰을 복합 계산하여 실제 데이터 자산에 도달 가능한 사용자의 실질적 최종 인가 범위이다.

</details>

- 멀티 클라우드(AWS S3, GCP GCS, Azure Blob), DB, **SaaS** 내 모든 데이터의 자동 발견 및 식별을 집행한다.
- **데이터 분류** 기술과 **데이터 계보** 분석을 결합하여 복제 방치된 민감 데이터의 원천 파악 및 삭제를 유도한다.
- IAM 직접 권한과 간접 상속 권한을 복합 분석한 **유효 접근** 권한을 도출해 과권한(Over-privileged) 위험을 차단한다.

#### 한줄 요약

- 민감 데이터 분류, 데이터 이동 계보 추적 및 유효 접근 권한 계산을 통해 미관리 그림자 데이터의 보안 위험을 제거한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **발견 엔진(Discovery Engine)**: API 및 비침투 스캔 기반으로 계정 내 모든 정형/비정형 데이터 저장소와 데이터베이스를 탐지하는 모듈이다.
- **분류 엔진(Classification Engine)**: NLP 및 딥러닝 알고리즘으로 PII, PCI-DSS 대상, 암호화 키 등 민감 데이터 종류와 등급을 자동 판정하는 모듈이다.
- **데이터 소유자(Data Owner)**: 식별된 데이터 위험에 대해 권한 축소, 암호화, 파기 승인 등 최종 조치 책임을 지는 현업/관리 주체이다.
- **마스킹(Masking)**: 개인정보 유출 방지를 위해 데이터 원본의 일부 또는 전체를 난수화/별표 처리하는 비식별화 기술이다.

</details>

```text
                         [저장소 연동]
                        /          \
               [발견·분류 엔진]  [접근·계보 분석]
                        \          /
                          [위험 우선순위]
                                |
                       [조치·소유자 연계]
```

선의 의미: 저장소 API 연동을 통해 발견/분류 엔진과 접근/계보 분석을 결합하고, 위험 우선순위를 도출해 소유자 조치를 연계하는 DSPM 구조이다.

| 구성요소 | 책임 |
|:---|:---|
| 저장소 연동 | 멀티 클라우드 Storage, RDBMS, NoSQL, SaaS API 커넥터 연동 |
| 발견·분류 엔진 | **발견 엔진**을 통한 미관리 데이터베이스 스캔 및 **분류 엔진**의 민감도 자동 분류 |
| 접근·계보 분석 | IAM 복합 분석으로 유효 접근 권한 산출 및 스냅샷/복제본 간 데이터 계보 매핑 |
| 위험 우선순위 | 민감도, 인터넷 노출 여부, 과권한 상태, 미암호화 여부를 결합한 위험 점수 산출 |
| 조치·소유자 연계 | **데이터 소유자** 지정, 조치 티케팅 연동, 권한 차단, **마스킹**, 격리 파기 집행 |

#### 한줄 요약

- 발견/분류 엔진과 계보 분석 모듈이 데이터 실체를 파악하고, 산출된 위험 점수에 따라 데이터 소유자가 보호 조치를 집행한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **비침투형 발견(Non-intrusive Discovery)**: DB 런타임 성능 저하 없이 Read-Only 메타데이터 및 스냅샷 복제본을 활용해 분석 스캔하는 기법이다.
- **잔여 노출(Residual Exposure)**: 보안 조치 실행 후에도 남아있는 잠재적 데이터 노출 및 취약성 잔여 위험 수준이다.
- **데이터 발견•민감도 분류(Data Discovery & Sensitivity Classification)**: 전체 데이터 자산을 탐지하고 민감 태그를 부여하는 단계이다.
- **유효 접근•데이터 계보 계산(Effective Access & Data Lineage Calculation)**: 실질적 접근 가능 사용자와 데이터 이동/복제 경로를 도출하는 단계이다.
- **데이터 위험 우선순위화(Data Risk Prioritization)**: 민감도, 노출 수준, 암호화 여부를 결합해 우선 조치 대상을 지정하는 단계이다.
- **보호 조치•소유 책임 확정(Remediation & Ownership Assignment)**: 자산 소유자를 지정하고 파기/권한 축소/마스킹 정책을 확정하는 단계이다.
- **보호 조치 적용(Remediation Execution)**: 확정된 보안 통제를 자동/수동 적용하고 잔여 노출을 모니터링하는 단계이다.

</details>

```text

      |

                  |

      |
      v

      |
      `-- 데이터 위험 근거
                  |

[데이터 소유자]
      |
      v

      |
      `-- 권한·마스킹·삭제 지시
                  |
                  v
[조치 시스템]
      |
      v

                  |

[DSPM 잔여 노출 검증]
```

### 동작 원리

1. **데이터 발견•민감도 분류**: 비침투 스캔으로 멀티 클라우드 저장소 내 데이터를 탐지하고 PII 등 민감도를 분류한다.
2. **유효 접근•데이터 계보 계산**: IAM 복합 권한과 스냅샷/복제 이동 경로를 추적하여 유효 접근자와 계보를 지도화한다.
3. **데이터 위험 우선순위화**: 퍼블릭 노출, 과권한, 암호화 부재, 민감도를 조합하여 조치 시급성을 산출한다.
4. **보호 조치•소유 책임 확정**: 데이터 소유자에게 티켓을 할당하고 권한 축소, 마스킹, 파기 방안을 결의한다.
5. **보호 조치 적용**: 조치를 집행하고 재스캔을 통해 잔여 노출 정합성을 재검증한다.

#### 한줄 요약

- 비침투 스캔 발견, 유효 접근 및 계보 계산, 위험 우선순위 산정, 소유자 조치 집행 및 잔여 노출 검증으로 순환 관리한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **클라우드 보안 형상 관리(Cloud Security Posture Management, CSPM)**: 클라우드 인프라 자원의 설정 오류 및 보안 통제를 스캐닝하는 보안 솔루션이다.
- **데이터 유출 방지(Data Loss Prevention, DLP)**: 네트워크, 엔드포인트 상에서 트래픽을 검사하여 민감 데이터 유출을 실시간 차단하는 솔루션이다.

</details>

| 데이터 보안 솔루션 | DSPM (Data Centric) | CSPM (Infra Centric) | DLP (Traffic/Host Centric) |
|:---|:---|:---|:---|
| 핵심 통제 대상 | 저장 데이터 실체, 민감도, 데이터 계보 | 클라우드 인프라 설정, 방화벽, S3 퍼블릭 노출 | 네트워크 트래픽, 엔드포인트 파일 반출 |
| 핵심 기능 | **DSPM** 기반 데이터 자동 발견•분류, 유효 권한 분석 | **CSPM** 기반 클라우드 오설정, IAM 설정 스캔 | **DLP** 기반 이메일, USB, 웹 업로드 실시간 차단 |
| 한계 | 정밀 분류 스캔 오탐 관리 필요 | 데이터 내부 내용(Content) 및 PII 존재 불지 | 방치된 저장 데이터(At-rest) 발견 불가능 |

#### 한줄 요약

- CSPM의 인프라 오설정 점검과 DLP의 실시간 유출 차단을 보완하여, DSPM은 저장 데이터 실체와 유효 접근 통제에 집중한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **ISO/IEC 27002 통제 5.12(ISO/IEC 27002 Control 5.12)**: 정보 자산의 분류, 식별, 등급 부여에 관한 국제 정보보호 표준 지침이다.
- **NIST SP 800-122**: 개인식별정보(PII) 기밀성 보존 및 기밀성 유출 영향 평가 가이드라인 표준이다.
- **개인 식별 정보(Personally Identifiable Information, PII)**: 주민등록번호, 이메일, 계좌번호 등 특정 개인을 식별할 수 있는 데이터이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 데이터 분류 체계 파편화 | **ISO/IEC 27002 통제 5.12** 준용 | 전사 자산에 대한 통일된 민감도 분류 스키마 정립 |
| PII 기밀성 유출 위험 | **NIST SP 800-122** 영향도 가이드 연계 | **PII** 데이터 우선 위험 산정 및 강화된 마스킹/암호화 적용 |
| 대용량 데이터 스캔 성능 영향 | 비침투형 스냅샷 스캔 및 API 샘플링 | 생산 DB 성능 저하 방지 및 지속적 가시성 확보 |

#### 한줄 요약

- ISO 27002 및 NIST SP 800-122 규격을 바탕으로 분류 체계를 정립하고, 비침투 스캔 방식으로 PII 데이터를 보호한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **데이터 위험 감소 성과(Data Risk Reduction Performance)**: 단순 오설정 탐지를 넘어 실질적인 민감 데이터 방치 건수 및 과권한 유출 경로 감소 실적 지표이다.

</details>

- **데이터 위험 감소 성과** 확보를 위해 저장 데이터 통제는 **DSPM**, 인프라 형상 제어는 **CSPM**, 트래픽 유출 차단은 **DLP**를 입체 적용한다.

#### 한줄 요약

- 멀티 클라우드 데이터 발견/분류, 유효 접근성 및 계보 분석, 과권한 차단 중심 데이터 보안 형상 관리(DSPM) 체계 구축 필수.
