## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **DSPM**: 저장 데이터의 민감도·위치·접근·복제·노출을 지속 분석하고 위험을 줄이는 관리 체계이다.
- **그림자 데이터**: 보안·거버넌스 관리 밖에서 생성·복제·보관되는 데이터이다.

</details>

- 정의/개념: **DSPM**은 저장 데이터의 위치·민감도·유효 접근·복제·노출을 지속 발견·분석해 위험을 줄이는 **데이터 보안 관리 체계**
- 배경/필요성: 미관리 그림자 데이터로 **과잉 접근·복제 확산**

#### 한줄 요약

- DSPM은 금고 설정만 보지 않고 어느 금고에 어떤 민감정보가 있고 누가 실제 열 수 있는지까지 연결해 본다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **데이터 분류·계보**: 내용과 업무 가치로 보호 등급을 정하고 데이터가 생성·변환·복제·이동한 경로를 연결하는 활동이다.
- **유효 접근**: 직접 권한뿐 아니라 상속·그룹·공개 설정을 모두 합친 실제 접근 가능 범위이다.

</details>

- **자동 데이터 발견**: 정형·비정형·SaaS 저장소 식별
- **민감도·계보 분류**: 내용·업무 문맥과 복제 경로 연결
- **위험 우선순위화**: 유효 접근·노출·보호 상태 결합

#### 한줄 요약

- 같은 공개 설정이라도 빈 테스트 파일보다 고객정보 복제본이 든 저장소를 먼저 고치도록 위험의 실제 크기를 따진다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **발견·분류 엔진**: 정형·비정형·SaaS 저장소에서 데이터 위치와 민감도를 자동 식별하는 기능이다.
- **데이터 소유자·마스킹**: 소유자는 등급·접근·보존·삭제 조치를 승인하고 마스킹은 민감한 일부 값을 알아볼 수 없게 가린다.

</details>

```mermaid
block-beta
  columns 3
  A["저장소 연동"]
  B["발견·분류 엔진"]
  C["접근·계보 분석"]
  D["위험 우선순위"]
  E["조치·소유자 연계"]
  A --> B --> C --> D --> E
  E --> A
```

| 구성요소 | 책임 |
|:---|:---|
| **저장소 연동** | 저장소·소유자·**복제본 연결** |
| **발견·분류 엔진** | 데이터 위치와 **민감도 식별** |
| **접근·계보 분석** | 유효 권한과 **이동 경로 계산** |
| **위험 우선순위** | 노출·민감도·**보호 상태 결합** |
| **조치·소유자 연계** | 권한·마스킹·**삭제·증적 관리** |

#### 한줄 요약

- 저장소를 읽어 민감한 데이터를 찾고 실제 접근자와 복제 경로를 계산해 가장 위험한 위치부터 고친다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **비침투형 발견**: 운영 데이터를 변경하지 않고 메타데이터나 최소 읽기 권한으로 저장 내용을 조사하는 방식이다.
- **잔여 노출**: 권한 축소·마스킹·삭제 같은 보호 조치 뒤에도 남아 있는 공개 또는 과잉 접근 위험이다.

</details>

```mermaid
sequenceDiagram
    participant S as 데이터 저장소
    participant D as DSPM
    participant O as 데이터 소유자
    participant C as 조치 시스템
    participant 검증기
    D->>S: 1. 최소 권한 메타데이터 조회
    S-->>D: 2. 내용·권한·암호화 정보 반환
    D-->>O: 3. 데이터 위험 근거 전달
    O->>C: 4. 권한·마스킹·삭제 승인
    C-->>검증기: 5. 조치 적용 결과 전달
    검증기-->>D: 잔여 노출 검증 결과
```

**동작 원리**

- **1. 최소 권한 메타데이터 조회**: 비침투 방식으로 저장소 검사
- **2. 내용·권한·암호화 정보 반환**: 소유자·공유·보호 상태 제공
- **3. 데이터 위험 근거 전달**: 민감도·계보·유효 접근 결과 제공
- **4. 권한·마스킹·삭제 승인**: 소유자가 보호 조치 결정
- **5. 조치 적용 결과 전달**: 재스캔과 잔여 노출 검증 자료 제공
#### 한줄 요약

- DSPM이 데이터를 바꾸지 않고 먼저 조사한 뒤 소유자에게 위험 근거를 보여 주고 승인된 보호 조치가 실제 반영됐는지 다시 확인한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **DSPM·CSPM·DLP**: DSPM은 저장 데이터와 실제 접근, CSPM은 클라우드 자원 설정, DLP는 데이터 사용·이동과 반출을 통제한다.

</details>

| 데이터 보안 유형 | DSPM | CSPM | DLP |
|:---|:---|:---|:---|
| 적용 기준 | 민감 데이터의 **위치·노출 파악** | 안전한 **클라우드 구성** | 실시간 **반출 탐지·차단** |
| 핵심 특징 | **저장 데이터·접근 분석** | **클라우드 자원 설정 평가** | 데이터의 **사용·이동 통제** |
| 한계 | **분류 오탐·스캔 공백** | **데이터 내용 미파악** | **미등록 저장 데이터 누락** |

#### 한줄 요약

- CSPM은 금고 설정, DLP는 문서 이동, DSPM은 금고 안의 내용과 실제 열쇠 소유자를 중심으로 본다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **ISO/IEC 27002 통제 5.12**: 정보의 기밀성·무결성·가용성과 이해관계자 요구에 따른 분류를 요구한다.
- **NIST SP 800-122·PII**: 개인을 식별할 수 있는 정보의 기밀성 영향을 평가하고 그 수준에 맞는 보호 조치를 선정하도록 안내한다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **정보 분류 기준 불일치** | **ISO/IEC 27002 통제 5.12 적용** | 민감도·보호 등급의 **일관화** |
| **개인식별정보 보호 누락** | **NIST SP 800-122 연계** | 영향 기반의 **보호 조치 선정** |
| **스캔 공백·과잉 권한** | **자산 대조·최소 읽기·재스캔** | 그림자 데이터와 **잔여 노출 축소** |

#### 한줄 요약

- DSPM은 관리 목록 밖의 클라우드 저장소에서 고객정보 복제본과 공개 권한을 함께 찾아 소유자를 확인하고 접근 차단·폐기를 수행한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **데이터 위험 감소 성과**: 발견 건수가 아니라 미관리 민감 데이터와 불필요한 접근·복제 경로를 실제로 제거한 정도이다.

</details>

- 저장 데이터·실제 접근은 **DSPM**, 자원 설정은 **CSPM**, 실시간 반출은 DLP 적용

#### 한줄 요약

- DSPM의 성과는 발견 건수보다 미관리 민감 데이터와 불필요한 접근·복제 경로를 실제로 얼마나 없앴는지로 판단한다.
