## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템 보안 취약점(Embedded Security Vulnerabilities)**: 전용 장치의 하드웨어•펌웨어•통신•갱신•물리 경로에서 기밀성•무결성•가용성을 훼손할 수 있는 약점이다.
- **공격면**: 공격자가 접근하거나 입력할 수 있는 통신•포트•갱신•물리 경로의 전체 범위이다.

</details>

- 정의/개념: 전용 장치의 하드웨어•펌웨어•통신•물리 경로에 존재하는 **임베디드 시스템 보안 취약점**이다.
- 배경/필요성: 공용 비밀•미패치 결함은 동일 모델 전체로 원격 공격을 확산시킨다.

#### 한줄 요약

- 오래 쓰고 고치기 어려운 장치는 작은 설계 실수도 같은 모델 전체의 장기 위험이 된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **하드코딩 자격증명**: 계정•암호•키를 펌웨어에 고정해 추출•재사용될 수 있는 결함이다.

</details>

- 자원 제약•장기 운영으로 보호 적용에 한계가 있다.
- 원격•로컬•물리•공급망의 **공격면**을 함께 관리한다.
- **하드코딩 자격증명**과 미서명 갱신은 장치군 전체로 위험을 확산시킨다.

#### 한줄 요약

- 네트워크뿐 아니라 디버그 포트, 펌웨어 파일, 칩 자체와 폐기 단계까지 보호해야 한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **JTAG(Joint Test Action Group)**: 칩 시험•디버깅에 사용하는 인터페이스이다.
- **UART(Universal Asynchronous Receiver-Transmitter)**: 직렬 진단 통신에 사용하는 인터페이스이다.
- **신뢰 루트**: 부팅 검증•키 보호 등 장치 신뢰가 시작되는 최소 하드웨어•코드 기반이다.

</details>

```text
임베디드 시스템 공격면
├─ 원격 통신•입력
├─ JTAG•UART 로컬 포트
├─ 펌웨어•부팅•갱신
├─ 하드웨어•물리 접근
└─ 제조•운영•폐기
```

| 구성요소 | 책임 |
|:---|:---|
| 원격 통신•입력 | 인증•암호화•파서 검증 |
| JTAG•UART 로컬 포트 | **JTAG**•**UART** 잠금과 승인 정비 접근 |
| 펌웨어•부팅•갱신 | 서명•버전•복구 검증 |
| 하드웨어•물리 접근 | **신뢰 루트**의 키 보호와 결함 주입 방어 |
| 제조•운영•폐기 | 장치별 비밀•패치•삭제 |

#### 한줄 요약

- 통신 입력부터 부팅 신뢰, 물리 포트, 장치별 키와 업데이트까지 공격 경로별 통제가 필요하다는 점이 핵심이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **결함 주입**: 전압•클록•빛을 교란해 연산 오류를 만들고 보안 검사를 우회하는 공격이다.
- **JTAG•UART 포트**: 노출 시 로컬 공격 경로가 되는 디버그•진단 포트이다.
- **위협 모델•보안 요구 수립**: 원격•로컬•물리•공급망 공격 경로와 영향을 분석하는 단계이다.
- **신뢰 루트•포트 정책 구현**: 장치별 키와 디버그 포트 접근 정책을 적용하는 단계이다.
- **서명 이미지•안전 갱신 구현**: 이미지 진위•버전과 실패 복구를 검증하는 단계이다.
- **퍼징•포트•결함 주입 시험**: 입력•디버그•물리 공격 경로를 시험하는 단계이다.
- **패치•지원종료 조건 확정**: 지원 기간•복구 절차•키 삭제 조건을 정하는 단계이다.

</details>

```text
장치 기능•운영 조건
   │
   ▼
1. 위협 모델•보안 요구 수립
   │
   ▼
2. 신뢰 루트•포트 정책 구현
   │
   ▼
3. 서명 이미지•안전 갱신 구현
   │
   ▼
4. 퍼징•포트•결함 주입 시험
   ├─ 결함 발견 ──► 설계•구현 보완 ──┐
   │                                  │
   └─ 시험 통과                       │
          │                           │
          ▼                           │
5. 패치•지원종료 조건 확정 ◄─────────┘
```

### 동작 원리

1. **위협 모델·보안 요구 수립**: 공격 경로·영향 분석
2. **신뢰 루트·포트 정책 구현**: 장치 키·포트 잠금
3. **서명 이미지·안전 갱신 구현**: 진위·버전 검증
4. **퍼징·포트·결함 주입 시험**: 공격 경로·위험 검증
5. **패치·지원종료 조건 확정**: 지원·복구·삭제 조건 확정

#### 한줄 요약

- 출시 직전 검사보다 설계 때 공격면을 줄이고 업데이트 실패와 지원 종료까지 준비하는 것이 핵심이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **메모리 안전성**: 허용 범위 밖의 읽기•쓰기와 잘못된 객체 접근을 방지하는 속성이다.

</details>

| 임베디드 취약점 | 코드 결함 | 자격증명 결함 | 부팅•갱신 결함 |
|:---|:---|:---|:---|
| 적용 기준 | 파서•저수준 코드 검증 | 제조•등록•폐기 키 관리 | 시작•원격 갱신 보호 |
| 핵심 특징 | **메모리 안전성** 결함으로 코드 실행 | **하드코딩 자격증명** 재사용 | 미검증 이미지 설치 |
| 한계 | 권한 상승•제어권 탈취 | 한 장치 분석의 전체 확산 | 악성•구형 이미지 지속 실행 |

> 요약: 코드•비밀•신뢰 경로별로 통제하는 것이 핵심이다.

#### 한줄 요약

- 실행 코드, 장치별 비밀, 시작•업데이트 경로는 서로 다른 시험과 보호가 필요하다는 점이 핵심이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ETSI(European Telecommunications Standards Institute)**: 유럽전기통신표준협회이다.
- **EN(European Standard)**: 유럽표준 문서 유형이다.
- **IoT(Internet of Things)**: 사물과 네트워크를 연결한 사물인터넷이다.
- **ETSI EN 303 645**: 소비자 IoT 제품의 기본 보안 요구표준이다.
- **IEC(International Electrotechnical Commission)**: 국제전기기술위원회이다.
- **IEC 62443-4-1**: 산업 제품의 보안 개발 생명주기 표준이다.
- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **IR(Internal Report)**: NIST의 내부보고서 문서 유형이다.
- **NIST IR 8259**: IoT 장치의 기능•제조 활동 보안 기준선이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 소비자 IoT에 공용 암호•업데이트 부재로 대규모 악용 | **ETSI**의 **EN**, **ETSI EN 303 645** 적용 | 공용 암호와 패치 위험 감소 |
| 산업 제품의 보안 활동이 개발 단계별로 단절 | **IEC**의 **IEC 62443-4-1** 적용 | 생명주기 통제 |
| 장치 기능•제조 활동 기준선이 없어 제품별 보호 편차 | **NIST**의 **IR**, **NIST IR 8259** 적용 | 보호 기준선 확보 |

- **IoT** 장치의 특성에 맞춰 소비자•산업 제품 표준을 선택한다.

#### 한줄 요약

- 양산 시 JTAG를 잠그고 장치별 비밀과 서명 갱신을 적용하며 승인된 정비 후 포트를 다시 잠근다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **전 생명주기 보안**: 제조•운영•갱신•지원 종료•폐기까지 장치의 신뢰와 복구 가능성을 유지하는 원칙이다.

</details>

- **전 생명주기 보안** 원칙에 따라 원격 입력에는 파서•인증, 로컬 경로에는 포트 잠금, 부팅•갱신에는 서명•롤백 방지를 적용한다.

#### 한줄 요약

- 제조부터 업데이트•지원 종료•폐기까지 장치의 신뢰와 복구 가능성을 이어가야 한다.
