## 미리 알고가기

- **임베디드 시스템**: 특정 기능을 수행하도록 하드웨어와 펌웨어를 결합한 전용 시스템
- **공격면**: 공격자가 접근하거나 입력을 보낼 수 있는 통신·포트·갱신·물리 경로의 전체 범위
- **메모리 안전성**: 허용 범위를 벗어난 메모리 읽기·쓰기와 잘못된 객체 접근을 방지하는 속성
- **하드코딩 자격증명**: 계정·암호·키를 펌웨어에 고정해 여러 장치가 공유하거나 추출될 수 있는 결함
- **JTAG (Joint Test Action Group)**: 칩 시험·디버깅을 위해 내부 상태와 메모리에 접근하는 하드웨어 인터페이스
- **UART (Universal Asynchronous Receiver-Transmitter)**: 장치의 진단 메시지와 명령을 주고받는 비동기 직렬 통신 인터페이스
- **결함 주입**: 전압·클록·빛 등을 교란해 연산 오류를 만들고 보안 검사를 우회하는 공격
- **신뢰 루트**: 부팅 검증·키 보호 등 장치 신뢰를 시작하는 최소 하드웨어·코드 기반
- **퍼징**: 비정상·무작위 입력을 반복해 충돌과 입력 검증 결함을 찾는 시험
- **JTAG·UART 읽기**: “제이태그·유아트”로 읽으며 칩 시험 그룹과 비동기 직렬 송수신기의 영문 명칭에서 온 표기임



## Ⅰ. 개요

- **정의/개념**: 장치 전 계층의 침해 가능 결함
- **배경/필요성**: 장기 배포·공용 결함의 장치군 확산

### 쉽게 이해하기 (학습용)

- 오래 쓰고 고치기 어려운 장치는 작은 설계 실수도 같은 모델 전체의 장기 위험이 됨

## Ⅱ. 특징

- 보호기법 적용이 자원 제약으로 어렵다.
- 물리적 접근 인터페이스를 고려해야 한다.
- 공용 자격증명으로 대규모 침해 확산 가능하다.
- 패치 중단·복구 실패가 장기 침해를 유발한다.

### 쉽게 이해하기 (학습용)

- 물리 포트부터 펌웨어 갱신까지 전 수명주기의 공격면을 줄여야 함

## Ⅲ. 아키텍처 및 구성요소

| 설계 요소 | 설명 |
|:---|:---|
| 통신 | 프로토콜 인증·입력을 처리함 |
| 로컬 | 디버그 포트로 펌웨어에 접근함 |
| 펌웨어 | 변조된 이미지 실행을 방지함 |
| 하드웨어 | 결함 주입 공격을 차단함 |
| 공급·운영 | 키 관리와 업데이트 절차를 통제함 |

```text
[공격면]
 원격: 통신·네트워크
 로컬: JTAG·UART
 공급망: 빌드·이미지
 물리: 결함 주입
```

### 쉽게 이해하기 (학습용)

- 네트워크 문뿐 아니라 개발 포트, 업데이트 파일과 칩 자체도 공격 경로가 될 수 있음

## Ⅳ. 원리 및 절차 흐름도

```text
분석
 ↓
축소
 ↓
구현
 ↓
검증
 ↓
관리
```

| 절차 | 설명 |
|:---|:---|
| 위협분석 | 접근 영향과 자산을 분석함 |
| 공격축소 | 서비스·포트·비밀을 제거함 |
| 신뢰구현 | 부팅·격리·서명을 구현함 |
| 보안검증 | 퍼징·물리 공격을 검증함 |
| 수명관리 | 복구·비밀 폐기를 운영함 |

### 쉽게 이해하기 (학습용)

- 출시 직전 검사보다 처음부터 공격 경로를 줄이고 안전한 업데이트와 폐기까지 설계해야 함

## Ⅴ. 종류 및 비교

| 비교축 | 코드 결함 | 자격증명 결함 | 부팅·업데이트 결함 |
|:---|:---|:---|:---|
| 핵심 특징 | 메모리·입력 오류로 코드 실행 | 공용·고정 비밀이 추출·재사용됨 | 검증되지 않은 펌웨어가 설치됨 |
| 적용 기준 | 통신 파서·저수준 코드를 검증할 때 | 제조·등록·수리·폐기 키를 관리할 때 | 부팅과 원격 갱신 경로를 보호할 때 |
| 주요 위험 | 권한 상승·장치 제어권 탈취 | 한 장치 분석이 전체 장치 침해로 확산 | 악성·구형 이미지로 지속적 장악 |

> 요약: 코드·설정·경로 결함별 대응 필요함

### 쉽게 이해하기 (학습용)

- 실행 중 코드, 장치 설정, 시작·업데이트 경로가 각각 다른 방식으로 침해될 수 있음

## Ⅵ. 실무 사례

- 위험에 맞는 경량 암호와 격리를 적용함
- 인증된 해제 절차를 마련하고 포트를 잠금함
- 장치 고유 비밀을 안전하게 관리함
- 복구 이미지와 실패 대응을 보장함

### 쉽게 이해하기 (학습용)

- 자원 한도 안에서 검증된 경량 암호와 격리를 선택함
- JTAG·UART는 인증된 유지보수 절차에서만 열리도록 잠금 상태를 관리함
- 장치마다 다른 비밀을 발급하고 수리·폐기 때 회수함
- 업데이트 실패 때 서명된 복구 이미지로 돌아갈 수 있게 시험함

## Ⅶ. 결론

- 공격면·장치별 비밀·업데이트를 전주기 관리함

### 쉽게 이해하기 (학습용)

- 출시 전 검사만으로 끝내지 않고 제조부터 업데이트·폐기까지 장치의 신뢰를 이어가야 함
