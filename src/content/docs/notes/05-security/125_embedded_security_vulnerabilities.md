## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **임베디드 시스템 보안 취약점(Embedded System Security Vulnerabilities / ETSI EN 303 645)**: 라우터, 스마트홈 IoT, CCTV, 차량용 ECU, 산업용 PLC 등 특정 목적을 위해 설계된 소형 컴퓨팅 장치의 하드웨어 설계, 펌웨어 소스코드, 디버깅 포트(JTAG/UART), 네트워크 통신망 및 무선(OTA) 업데이트 채널에 존재하는 보안 결함.
- **자원 제약성과 롱테일 수명주기 결함(Resource Constraints & Long Lifecycle Defect)**: 저사양 CPU와 제한된 메모리로 인해 고성능 암호화 및 EDR 에이전트 구동이 불가능하고, 한번 출시되면 10년 이상 방치되어 보안 패치 지원이 단절됨에 따라 동일 모델 수백만 대가 미라이(Mirai) 봇넷 등 대규모 디도스 공격의 숙주로 악용되는 구조적 결함.

</details>

- 정의/개념: 기기 전체 공격 표면(Attack Surface)을 방어하기 위해 **신뢰 루트(Hardware RoT) 기반 보안 부팅 $\rightarrow$ 물리적 디버그 포트(JTAG/UART) 하드웨어 차단 $\rightarrow$ 디지털 서명 기반 안전한 OTA 펌웨어 갱신 $\rightarrow$ 하드코딩 자격증명 제거 $\rightarrow$ 전 수명주기(제조~폐기) 암호키 폐기** 를 집행하는 **임베디드 하드웨어·펌웨어 보안 아키텍처**
- 배경/필요성: 자원 제약과 장기 운용으로 **패치·보안 에이전트 적용 제약**

#### 한줄 요약
- 하드웨어 RoT, JTAG 포트 봉인, 서명된 OTA 펌웨어 갱신을 통해 임베디드 전 수명주기 취약점을 통제한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **임베디드 4대 핵심 공격 표면 (Attack Surfaces)**:
  1. **Network Interface**: 개방된 포트(Telnet, HTTP), 통신 암호화 부재, 버퍼 오버플로우.
  2. **Physical / Debug Interface**: JTAG/UART 핀을 통한 펌웨어 무단 덤프 및 루트 쉘 탈취.
  3. **Firmware & Storage**: 펌웨어 내 하드코딩된 비밀번호/API 키, 미서명 펌웨어 변조.
  4. **Side-channel & Hardware**: 전압 글리치(Glitch), 전력 분석(DPA)을 통한 암호키 추출.

</details>

- **하드코딩 자격증명(Hardcoded Credentials)의 원천 제거**: 공장 출하 시 기기마다 고유한 비밀번호(Unique Default Password) 및 암호화 키를 프로비저닝하여 무차별 대입 공격 차단
- **물리적 디버그 포트 봉인(Port Lockout)**: 제조 완료 후 JTAG/UART 핀의 물리적 퓨즈(eFuse)를 블로잉(Blowing)하여 외부 장비 연결을 통한 펌웨어 역공학 차단
- **안티 롤백(Anti-rollback) 보안 부팅**: 서명 검증뿐만 아니라 하드웨어 eFuse 카운터를 활용하여 알려진 취약점이 있는 구버전 펌웨어로의 다운그레이드 공격 원천 방어

#### 한줄 요약
- 4대 공격 표면 통제, 기기별 고유 인증키 부여, JTAG/UART eFuse 봉인, 안티 롤백 보안 부팅을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **임베디드 보안 방어 4대 핵심 컴포넌트**:
  1. **Hardware Root of Trust (RoT)**: 변조 불가능한 보안 부트스트랩 ROM 및 Secure Element.
  2. **Memory Safety & Secure OS**: C/C++ 버퍼 보호 및 Microkernel/TrustZone 격리 환경.
  3. **Cryptographic Engine (KCMVP/AES)**: 하드웨어 암호 가속기 및 안전한 키 저장소(Keystore).
  4. **Secure OTA Update Manager**: 공개키 전자서명 검증 및 롤백 방지 업데이트 매니저.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 원격 통신 및 애플리케이션 계층 (Network & App Layer) ]             │
│  ├─ TLS 1.3 암호화 통신, 불필요 포트(Telnet/SSH) 기본 비활성화           │
│  └─ [ 엄격한 입력 파서 검증 ➔ 버퍼 오버플로우 및 명령 주입 원천 차단 ]   │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (시스템 제어 및 데이터 처리)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 펌웨어 및 OS 런타임 계층 (Firmware & Runtime Layer) ]              │
│  ├─ 하드코딩 계정 제거 ➔ 기기별 고유 랜덤 패스워드 강제 주입            │
│  └─ [ 안전한 OTA 갱신: ECDSA 서명 검증 + eFuse 안티 롤백 버전 락킹 ]     │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (하드웨어 인터페이스 및 버스 통제)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 물리 인터페이스 계층 (Physical & Debug Interface Layer) ]           │
│  └─ [ JTAG / UART 디버그 핀 eFuse 블로잉(Blowing) ➔ 물리 덤프 원천 차단 ]│
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (하드웨어 보안 앵커)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 하드웨어 신뢰 루트 계층 (Hardware Root of Trust, RoT) ]             │
│  └─ [ Secure Boot ROM ➔ 불변의 공개키 해시 기반 단계별 무결성 체인 검증]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 신뢰 루트(RoT)를 시작으로 물리 포트를 봉인하고 펌웨어와 네트워크 계층까지 전 계층을 방어하는 계층적 구조

| 계층 | 주요 취약점 및 위협 | 핵심 방어 통제 기술 | 비고 |
|:---|:---|:---|:---|
| **네트워크 인터페이스** | 취약한 원격 서비스(Telnet), 버퍼 오버플로우, 평문 통신 | TLS 1.3 강제, 불필요 데몬 제거, 입력값 경계 검사 | Network |
| **펌웨어 및 업데이트** | 하드코딩 자격증명, 미서명 펌웨어 주입, 구버전 롤백 공격 | ECDSA 전자서명 검증, eFuse 안티 롤백, 안전한 듀얼 뱅크 복구 | Firmware |
| **디버그 포트 (물리)** | JTAG/UART 핀을 통한 플래시 메모리 덤프 및 루트 쉘 획득 | eFuse Blowing(물리적 비활성화), 패스워드 인증 락 | Hardware Pin |
| **신뢰 루트 (RoT)** | 결함 주입(Glitch), 부트로더 변조, 암호키 메모리 추출 | Secure Boot Chain of Trust, 하드웨어 보안 모듈(HSM) | Root Anchor |
| **수명주기 거버넌스** | 취약점 패치 중단, 기기 폐기 시 플래시 잔여 기밀 유출 | SBOM 관리, 취약점 공시 정책, 암호화 키 제로화(Zeroization)| Lifecycle |

#### 한줄 요약
- 네트워크 통신 암호화, 전자서명 OTA 펌웨어 갱신, JTAG eFuse 봉인, 하드웨어 RoT 보안 부팅으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임베디드 보안 개발 및 수명주기 5단계 프로세스**:
  1. 위협 모델링 및 전방위 공격 표면 분석 (Threat Modeling)
  2. 하드웨어 RoT 및 보안 부팅 체인 설계 (Secure Boot Design)
  3. 시큐어 코딩 및 하드코딩 자격증명 제거 (Implementation)
  4. 펌웨어 퍼징 및 물리적 결함 주입(Fault Injection) 테스트
  5. 보안 OTA 패치 배포 및 수명 종료(EoL) 암호키 폐기

</details>

```text
1. [위협 모델링] IoT 카메라 공격 표면(Wi-Fi, RTSP, UART, Flash 칩) 식별 ➔ 보안 요구사항 도출
            │
            ▼
2. [하드웨어 신뢰 루트(RoT) 구축]
    ├─ MCU 내부 OTP(One-Time Programmable) 메모리에 제조사 루트 공개키 해시 저장
    └─ [출하 전 JTAG/UART 디버그 인터페이스 eFuse를 영구 단선(Blow) 처리]
            │
            ▼
3. [시큐어 펌웨어 개발]
    ├─ 소스코드 내 평문 비밀번호 및 마스터 암호화 키 완전 배제
    └─ [기기 부팅 시 Flash 암호화(AES-XTS) 및 ECDSA 전자서명 검증 체인 구축]
            │
            ▼
4. [보안성 테스트 및 결함 주입 검증]
    ├─ 네트워크 인터페이스 대상 프로토콜 퍼징(Fuzzing) 수행
    └─ [전압 글리치(Voltage Glitch) 및 레이저 결함 주입 시도 ➔ RoT 방어력 검증]
            │
            ▼
5. [안전한 OTA 운영 및 폐기]
    ├─ 듀얼 뱅크(A/B 파티션) 기반 안전한 무중단 롤백 OTA 펌웨어 갱신 배포
    └─ [기기 수명 종료 폐기 시 내부 암호화 마스터 키 제로화(Zeroization) 수행]
```

**동작 원리**

1. **물리적 접점 원천 봉쇄**: 디버그 핀을 물리적으로 영구 차단하여 공격자의 현장 케이블 연결 해킹 방어
2. **신뢰의 사슬(Chain of Trust) 확립**: ROM $\rightarrow$ 부트로더 $\rightarrow$ OS $\rightarrow$ 앱 순으로 상위 단계가 하위 단계의 서명을 검증
3. **다운그레이드 공격 차단**: 안티 롤백 카운터를 통해 과거 취약점이 포함된 공식 펌웨어 재설치 방어
4. **회복탄력적 갱신(Dual-Bank)**: OTA 펌웨어 업데이트 도중 전원 차단 시 이전 정상 펌웨어로 자동 롤백
5. **데이터 영구 보호**: 기기 폐기 시 물리적 메모리를 분해하더라도 암호화 키 파기를 통해 평문 판독 불가

#### 한줄 요약
- 위협 모델링, 하드웨어 RoT 구축, 시큐어 펌웨어 개발, 결함 주입 테스트, 안전한 OTA 및 키 폐기 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **임베디드 주요 3대 취약점 영역 비교**:
  - 메모리/코드 취약점: C/C++ 버퍼 오버플로우를 통한 임의 코드 실행.
  - 자격증명 취약점: 소스코드 내 하드코딩된 계정 및 마스터 키 유출.
  - 부팅/업데이트 취약점: 변조된 펌웨어 주입 및 취약 구버전 롤백.

</details>

| 비교 항목 | 메모리/코드 취약점 | 하드코딩 자격증명 취약점 | 펌웨어 부팅/업데이트 취약점 |
|:---|:---|:---|:---|
| **취약점 본질** | **스택/힙 버퍼 오버플로우, Use-After-Free** | **소스코드 내 평문 계정/비밀번호 고정** | **미서명 펌웨어 실행, 안티 롤백 부재**|
| **공격 메커니즘** | 원격 악성 페이로드 주입 및 쉘 획득 | 펌웨어 역공학으로 추출 후 원격 로그인 | 가짜 백도어 펌웨어 플래싱, 다운그레이드 |
| **피해 파급력** | 단일 기기 제어권 탈취 및 프로세스 크래시 | **동일 모델 수백만 대 전역 봇넷 감염** | **영구적인 하드웨어 백도어 장착(루팅)** |
| **핵심 대책** | **메모리 안전 언어(Rust), 경계 검사, ASLR**| **기기별 고유 비밀번호 주입, TPM/HSM** | **Secure Boot, ECDSA 서명, eFuse 카운터** |

#### 한줄 요약
- 메모리 취약점은 버퍼 오버플로우 방어, 자격증명 취약점은 고유 키 주입, 부팅 취약점은 Secure Boot로 해결한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **ETSI EN 303 645 (소비자 IoT 보안) 및 IEC 62443-4-1 (산업용 제어시스템 보안 개발)**: 임베디드 및 IoT 제품 보안 요구사항 국제 표준.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| IP 카메라에 공용 관리자 비밀번호('admin/1234')가 하드코딩되어 **수백만 대가 미라이(Mirai) 봇넷에 감염되어 대규모 디도스 공격 숙주로 악용** | **ETSI EN 303 645 10대 기본 요구사항 준수, 공용 기본 패스워드 전면 금지 및 기기별 고유 랜덤 패스워드 공장 주입 강제** | 봇넷 대규모 전염 100% 원천 차단 및 계정 탈취 방어 |
| 기판에 노출된 JTAG/UART 디버그 핀을 통해 해커가 물리적으로 연결하여 **플래시 메모리를 무단 덤프하고 내부 암호화 마스터 키를 탈취** | **제조 공정 완료 후 eFuse Blowing을 통해 JTAG/UART 인터페이스를 영구 단선 처리하고 플래시 암호화(Flash Encryption) 적용** | 물리적 디버그 포트 악용 및 펌웨어 역공학 100% 차단 |
| 공격자가 알려진 과거 취약점이 포함된 공식 구버전 펌웨어로 다운그레이드하여 **최신 보안 패치를 무력화하고 기기 제어권 탈취 (Rollback Attack)** | **하드웨어 eFuse 기반 안티 롤백(Anti-rollback) 카운터를 적용하여 현재 버전보다 낮은 버전의 펌웨어 부팅을 기계적으로 차단** | 취약 펌웨어 강제 다운그레이드 공격 100% 원천 봉쇄 |

#### 한줄 요약
- 고유 패스워드로 봇넷을 막고, JTAG eFuse 봉인으로 덤프를 방지하며, 안티 롤백 카운터로 다운그레이드를 차단한다.

## Ⅶ. 결론

- 물리 접근은 **JTAG 봉인**, 원격 갱신은 **서명·안티 롤백** 적용

#### 한줄 요약
- 하드웨어 RoT 보안 부팅과 JTAG eFuse 봉인 및 안티 롤백 전자서명 OTA를 통해 완벽한 임베디드 보안을 완성한다.
