## 미리 알고가기

- **보안 부팅(Secure Boot)**: 신뢰 키와 폐기 목록으로 부트 이미지의 서명을 검증하여 허가된 코드만 실행하는 부팅 보안 기술이다.
- **통합 확장 펌웨어 인터페이스(Unified Extensible Firmware Interface, UEFI)**: 하드웨어 초기화와 운영체제 부팅 서비스를 제공하고 보안 부팅 변수를 관리하는 펌웨어 인터페이스이다.
- **플랫폼 키(Platform Key, PK)**: 보안 부팅 정책의 소유권과 키 교환 키 변경 권한을 설정하는 최상위 키이다.
- **키 교환 키(Key Exchange Key, KEK)**: 허용 서명 데이터베이스와 폐기 목록의 갱신 권한을 통제하는 키이다.
- **db**: 허용 서명·해시를 저장함
- **dbx**: 폐기 서명·해시를 저장함
- **Trusted Boot**: 운영체제가 다음 구성요소를 검증하며 신뢰 사슬을 이어가는 부팅 방식
- **Measured Boot**: 부팅 구성요소의 측정값을 TPM에 기록해 원격 또는 후속 검증에 쓰는 방식
- **TPM (Trusted Platform Module)**: 암호 키와 부팅 측정값을 보호하는 보안 칩
- **부트킷**: 운영체제보다 먼저 실행돼 부팅 과정과 보안 기능을 조작하는 악성코드
- **런타임 보호**: 부팅이 끝난 뒤 실행 중 코드·메모리·행위를 보호하는 통제



## Ⅰ. 개요

- 정의: UEFI 신뢰 정책 기반 **부트 이미지 검증**
- 기존 한계: 부팅 전 악성코드의 **보안 통제 우회**

### 쉽게 이해하기 (학습용)

- 컴퓨터가 켜질 때 다음 프로그램의 서명과 금지 목록을 확인해 승인된 코드만 넘겨주는 방식임

## Ⅱ. 특징

- PK·KEK 기반 **정책 소유·갱신 권한**
- db·dbx 기반 **허용·폐기 대상 판정**
- 펌웨어부터 부트로더까지 **신뢰 사슬**

### 쉽게 이해하기 (학습용)

- 서명이 유효해도 나중에 취약성이 발견될 수 있어 금지 목록과 인증서를 계속 갱신해야 함

## Ⅲ. 아키텍처 및 구성요소

```text
[PK]
 |
[KEK]
 |
[db] [dbx]
 |    |
[이미지 검증]
```

| 설계 요소 | 설명 |
|:---|:---|
| PK | 플랫폼 정책 소유권 설정 |
| KEK | db·dbx 갱신 권한 검증 |
| db | 허용 서명·해시 저장 |
| dbx | 폐기 서명·해시 저장 |
| 이미지 검증기 | 서명 체인·정책 판정 |

### 쉽게 이해하기 (학습용)

- 소유권 키가 목록 변경을 통제하고 허용·금지 목록이 실제 부트 파일의 실행을 결정함

## Ⅳ. 원리 및 절차 흐름도

```text
등록
 ↓
설정
 ↓
검증
 ↓
차단
 ↓
복구
```

| 절차 | 설명 |
|:---|:---|
| 등록 | PK·KEK와 신뢰 인증서를 등록함 |
| 설정 | db에 허용 대상을 등록함 |
| 검증 | 서명을 db·dbx 정책과 대조함 |
| 차단 | 검증 실패 시 실행을 차단함 |
| 복구 | 인증서·dbx 갱신과 복구 수행함 |

### 쉽게 이해하기 (학습용)

- 신뢰 키로 부트 파일을 검증하고 실패 시 복구 경로로 전환함

## Ⅴ. 종류 및 비교

| 부팅 신뢰 기술 | Secure Boot | Trusted Boot | Measured Boot |
|:---|:---|:---|:---|
| 적용 기준 | 부트로더·드라이버 실행을 통제할 때 | OS 구성요소까지 신뢰 사슬을 이을 때 | 부팅 상태를 사후·원격 증명할 때 |
| 핵심 특징 | 미승인 부트 이미지 차단 | OS 구성요소 연속 검증 | TPM에 부팅 측정값 기록 |
| 한계 | 키·dbx 오류 시 부팅 차단 | OS 검증 정책 침해 | 측정만으로 실행 차단 불가 |

> 요약: UEFI 정책 기반 부트 무결성 확보 필요

### 쉽게 이해하기 (학습용)

- Secure Boot는 실행 차단, Trusted Boot는 연속 검증, Measured Boot는 측정을 기록함

## Ⅵ. 실무 사례

1. 단말 부팅의 **필수 서명자만 허용**

### 쉽게 이해하기 (학습용)

- 단말은 제조사와 조직이 승인한 부트로더·커널 서명만 허용하고 폐기 목록에 포함된 취약 서명자는 부팅 전에 거부한다.

## Ⅶ. 결론

- 부팅 전 악성 코드의 실행을 막기 위해 신뢰 키·서명 체인·폐기 목록·버전·복구 경로를 검토하여, 승인된 소프트웨어만 실행하는 Secure Boot를 운영해야 한다.

### 쉽게 이해하기 (학습용)

- 핵심은 서명 기능 자체보다 누구를 신뢰하고 언제 폐기할지를 안전하게 운영하는 데 있음
