## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **보안 오케스트레이션 플레이북(Security Orchestration Playbook, SOP)**: 보안 경보 유형별 위협 보강, 분석, 승인, 조치, 복구 절차 및 분기 조건을 표준화하여 보안 플랫폼에서 실행 가능한 자동화 워크플로우 정의서.
- **SOAR(Security Orchestration, Automation and Response)**: 이기종 보안 도구들을 API로 연동하여 정형화된 플레이북을 실행하고 대응하는 통합 보안 플랫폼.

</details>

- 정의/개념: 경보별 분석·승인·조치를 연결하는
  **보안 오케스트레이션 플레이북**
- 배경/필요성: 수동 대응 지연과 도구별 절차 차이로
  발생하는 **대응 일관성** 저하

#### 한줄 요약

- 조건부 자동화와 **승인·롤백**을 결합한 대응 절차

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **사람 참여**: 업무 영향이 큰 자동 조치를 담당자가 확인•승인하는 방식이다.
- **롤백**: 자동 조치 실패나 오탐 발생 시 이전 상태로 되돌리는 기능이다.
- **API(Application Programming Interface)**: 보안 도구가 조회•명령•결과를 주고받는 연결 경계이다.

</details>

- API 및 표준 명령 기반 오케스트레이션 수행.
- 위험도에 따른 자동•승인•수동 대응 경로 차등화 및 고영향 조치 시 사람 참여(Human-in-the-loop) 적용.
- 롤백(Rollback), 권한 통제 및 감사 로그를 통한 자동화 제어 체계 확보.

#### 한줄 요약

- 경보 위험도에 따른 대응 경로(자동•승인•수동) 분기 및 자동 조치 실패 시 롤백 체계 수립.

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **오케스트레이션**: 서로 다른 보안 도구의 조회•판단•조치를 하나의 흐름으로 연결하는 기능이다.

</details>

```text
보안 오케스트레이션 플레이북
├─ 경보 및 요청 트리거
├─ 자산 및 위협정보 보강
├─ 위험도 분기 및 사람 승인
├─ 최소권한 조치 및 롤백
└─ 사건 티켓 및 감사로그
```

| 구성요소 | 책임 |
|:---|:---|
| 경보•요청 트리거 | 실행 조건•중복•범위 결정 |
| 자산•위협정보 보강 | 사용자•평판•업무 맥락 결합 |
| 위험 분기•사람 승인 | **사람 참여**가 필요한 경로 선택 |
| 최소권한 조치•롤백 | 차단•격리 후 **롤백** 가능성 확보 |
| 사건 티켓•감사로그 | 결정•API 결과•담당자 기록 |

- **SOAR**에서 **오케스트레이션** 흐름을 실행하고 각 도구의 결과를 사건 기록에 연결한다.

#### 한줄 요약

- 보안 자동화의 본질은 대응 속도뿐만 아니라, 오탐/실패 시 즉각적인 복구(롤백)와 결정 근거(감사)를 보존하는 통제력 확보임.

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **SIEM(Security Information and Event Management)**: 보안 이벤트를 수집•분석해 경보를 만드는 체계이다.
- **EDR(Endpoint Detection and Response)**: 단말 위협을 탐지•격리•대응하는 체계이다.
- **경보 보강•위험 수준 산정**: 경보에 자산•사용자•위협정보를 결합해 대응 위험을 평가하는 단계이다.
- **대응 경로•승인 여부 결정**: 위험과 업무 영향에 따라 자동•승인•수동 경로를 정하는 단계이다.
- **최소권한 대응 명령 생성**: 필요한 대상과 범위만 제한하는 조치 명령을 만드는 단계이다.
- **조치 실행•롤백 검증**: 대응 효과와 실패•오탐 시 복구 가능성을 확인하는 단계이다.
- **사건 증적•성과 지표 기록**: 결정 근거•처리 시간•오탐•실패율을 보존하는 단계이다.

</details>

```text
보안 경보
   │
   ▼
1. 경보 보강·위험 수준 산정
   │
   ▼
2. 대응 경로·승인 여부 결정
   ├─ 저위험 및 고신뢰 ────── 자동 대응
   ├─ 고영향 및 승인 가능 ─── 승인 대응
   └─ 복잡 판단 및 저신뢰 ─── 수동 지원
                   │
                   ▼
3. 최소권한 대응 명령 생성
   │
   ▼
4. 조치 실행·롤백 검증
   │ 실패 또는 오탐
   ├──────────────► 롤백
   │ 성공
   ▼
5. 사건 증적·성과 지표 기록
   │
   ▼
대응 결과
```

### 동작 원리

1. **경보 보강·위험 수준 산정**: 자산·업무 영향 결합
2. **대응 경로·승인 여부 결정**: 자동·승인·수동 분기
3. **최소권한 대응 명령 생성**: 대상별 제한 명령 생성
4. **조치 실행·롤백 검증**: 효과·실패·복구 상태 검증
5. **사건 증적·성과 지표 기록**: 근거·오탐·실패율 보존

#### 한줄 요약

- 즉시 자동 차단보다 단계적 관찰과 승인 절차를 통해 안전성이 검증된 범위부터 점진적으로 자동화 적용.

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **완전 자동 대응**: 조건을 충족하면 사람 승인 없이 실행하는 방식이다.
- **승인 기반 대응**: 사람이 확인한 뒤 조치를 실행하는 방식이다.
- **수동 지원 대응**: 자동 보강 후 사람이 판단•실행하는 방식이다.

</details>

| 플레이북 실행 방식 | 완전 자동 | 승인 기반 | 수동 지원 |
|:---|:---|:---|:---|
| 적용 기준 | 반복적이고 되돌릴 수 있는 저위험 조치 | 업무 영향이 큰 신속 조치 | 복잡하거나 자동화가 미성숙한 판단 |
| 핵심 특징 | **완전 자동 대응**으로 즉시 조치 | **승인 기반 대응**으로 확인 후 조치 | **수동 지원 대응**으로 분석가 실행 |
| 한계 | 오탐의 대규모 차단 확산 | 승인에 따른 대응 지연 | 처리 편차와 분석가 부담 |

> 요약: 대상 위험도와 자동화 성숙도에 따라 선택하는 것이 핵심이다.

#### 한줄 요약

- 고신뢰성 작업은 완전 자동화하되, 업무 중단 리스크가 큰 조치는 사람의 최종 확인 및 승인 절차 필수 적용.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **OASIS(Organization for the Advancement of Structured Information Standards)**: 구조화 정보표준 촉진기구이다.
- **CACAO(Collaborative Automated Course of Action Operations)**: 보안 플레이북의 공유 스키마이다.
- **OpenC2(Open Command and Control)**: 보안 장치에 표준 명령을 전달하는 언어 규격이다.
- **NIST(National Institute of Standards and Technology)**: 미국 국립표준기술연구소이다.
- **SP(Special Publication)**: NIST가 발행하는 특별간행물이다.
- **CSF(Cybersecurity Framework)**: 사이버보안 위험관리 결과 프레임워크이다.
- **NIST SP 800-61**: CSF 기반 사고대응 생명주기 지침이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 플레이북 구조가 제품마다 다르면 공유•재사용 곤란 | **OASIS**의 **CACAO** 적용 | 절차 구조화•상호운용 확보 |
| 보안 조치 명령이 도구별로 달라 연계 오류 | **OpenC2** 적용 | 대응 명령 표준화 |
| 자동화가 사고대응 생명주기와 분리되면 통제 누락 | **NIST**의 **SP**, **NIST SP 800-61**, **CSF** 연계 | 사고대응 통합 |

#### 한줄 요약

- 플레이북은 단말의 악성 행위와 업무 중요도를 확인하고 승인 조건을 충족하면 최소 권한 API로 격리하며 실행 결과와 롤백 정보를 기록한다.

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **안전한 자동화**: 신뢰도•업무 영향•승인•롤백을 함께 통제하는 자동화 원칙이다.

</details>

- 저위험·가역 조치는 **자동**, 고영향 조치는 **승인** 적용

#### 한줄 요약

- 신속한 자동 대응보다 오탐 및 조치 오류 시 즉시 중단·복구가 가능한 제어 중심의 안전한 보안 오케스트레이션 체계 적용.
