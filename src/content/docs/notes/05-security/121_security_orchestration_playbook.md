## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **보안 오케스트레이션 플레이북(Security Orchestration Playbook / OASIS CACAO)**: 보안관제센터(SOC)에 인입되는 대량의 보안 경보(Alert)를 신속하고 일관되게 처리하기 위해, 위협 첩보 보강(Enrichment), 위험도 분석, 대응 조치(격리/차단), 인간 승인(Approval), 롤백(Rollback) 및 보고 절차를 조건부 분기 로직과 기계 가독형 스크립트로 표준화한 자동화 워크플로우.
- **수동 관제 피로도 및 오탐 자동화 차단 결함(Manual Fatigue & Unsafe Automation Defect)**: 수동 관제에 의존할 경우 일일 수만 건의 경보에 대한 대응 시간(MTTR)이 지연되는 반면, 무조건적인 100% 자동 차단을 적용할 경우 정상 결제 서버나 C-Level 단말을 오탐 격리하여 비즈니스 중단 사고로 이어지는 양면적 구조적 결함.

</details>

- 정의/개념: 이기종 보안 솔루션 간의 API 연동을 기반으로 **SIEM 경보 인입 $\rightarrow$ CTI 위협 정보 심층 보강 $\rightarrow$ 위험도 기반 3단계 분기(완전 자동 / 인간 승인 / 수동) $\rightarrow$ 최소 권한 핀셋 차단(방화벽/EDR) $\rightarrow$ 오탐 시 즉각 롤백(Rollback) $\rightarrow$ 감사 로그 및 성과 지표(MTTR) 기록** 을 집행하는 **보안 운영 자동화 및 오케스트레이션 아키텍처**
- 배경/필요성: 보안 관제 인력 부족과 공격 속도의 가속화에 대응하여, 안전 통제선(Safe Automation)을 유지하면서 평균 대응 시간(MTTR)을 초 단위로 단축할 요구

#### 한줄 요약
- SOAR 플레이북은 CTI 보강과 위험도 기반 인간 개입(Human-in-the-loop) 분기 및 롤백을 통해 안전한 보안 자동화를 구현한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **SOAR 플레이북의 핵심 3대 운영 원칙**:
  - **인간 개입 통제 (Human-in-the-loop)**: 고영향 자산(핵심 DB, 임원 단말) 대상 조치 시 관제 팀장의 명시적 승인을 강제하는 브레이크 메커니즘.
  - **오탐 롤백 메커니즘 (Rollback Mechanism)**: 자동 차단 명령 실패 또는 오탐 판명 시 즉각 조치 이전 상태로 복원하는 가역성 보장.
  - **표준 상호운용성 (OASIS CACAO / OpenC2)**: 벤더 종속성을 탈피하여 JSON 기반 표준 플레이북 스키마 및 공통 명령 제어 프로토콜 채택.

</details>

- **조건부 위험 기반 다단계 분기**: 저위험 단순 경보는 100% 완전 자동화(Fully-Auto)로 처리하고, 고위험 비즈니스 영향 조치는 승인 기반(Approval-based)으로 격리
- **이기종 솔루션 API 오케스트레이션**: 방화벽, EDR, SIEM, CTI, Active Directory, 백신 등 파편화된 도구들을 단일 파이프라인으로 제어
- **철저한 감사 추적성(Auditability)**: 모든 자동 실행 단계의 입력값, API 호출 결과, 승인자 서명, 타임스탬프를 불변 티켓 원장에 영구 기록

#### 한줄 요약
- 위험 기반 분기, 인간 승인 개입, 오탐 롤백 보장, 표준 CACAO/OpenC2 기반 상호운용성을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **SOAR 플레이북 4대 핵심 아키텍처 레이어**:
  1. **Trigger & Ingestion Layer**: SIEM/EDR 경보 수집 및 중복 경보 스톰(Alert Storm) 억제.
  2. **Enrichment Layer**: VirusTotal, 내부 CMDB, IP 평판 CTI 교차 분석.
  3. **Decision & Branching Layer**: 위험도 스코어링 및 Human-in-the-loop 승인 분기.
  4. **Action & Rollback Layer**: OpenC2 기반 방화벽 IP 차단, EDR 단말 격리, 장애 시 자동 롤백.

</details>

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 1. 경보 트리거 및 수집 계층 (Trigger & Alert Ingestion) ]              │
│  └─ SIEM / EDR에서 침해 의심 경보 수신 ➔ 중복 이벤트 디바운싱(Debouncing) │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (경보 파싱 및 트리거 발동)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 2. 컨텍스트 보강 계층 (Threat Enrichment & Contextualization) ]        │
│  ├─ [ CTI 평판 조회 ] ➔ 외부 VirusTotal / Shodan 악성 IP/도메인 스코어링  │
│  └─ [ 내부 CMDB 자산 조회 ] ➔ 호스트 중요도(Tier 1/2/3) 및 소유자 매핑  │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │ (위험 등급 및 영향도 산출)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 3. 위험도 기반 3단계 실행 분기 계층 (Decision & Approval Branching) ]  │
├───────────────────┬───────────────────┬─────────────────────────────────┤
│ [ 1. 완전 자동화 ]│ [ 2. 인간 승인 ]  │ [ 3. 수동 지원 (Manual) ]       │
│ ├─ 저영향/고신뢰  │ ├─ [ Human-loop ] │ ├─ 복합/저신뢰 시나리오         │
│ └─ 악성 IP 즉시차단│ └─ 팀장 승인 후격리│ └─ 첩보 보강 후 분석관 이관     │
└───────────────────┴───────────────────┴─────────────────────────────────┘
                                     │ (OpenC2 표준 명령 발행)
                                     ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 4. 액션 실행 및 롤백 계층 (Action Execution & Rollback Engine) ]       │
│  ├─ 방화벽 차단 및 EDR 호스트 네트워크 격리 API 호출                     │
│  └─ [ API 오류 또는 오탐 확인 시 ➔ 1초 내 방화벽 룰 자동 롤백(Rollback) ]│
└─────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 경보 인입 후 CTI와 자산 맥락으로 보강하고, 3단계 분기를 거쳐 액션을 실행하며 오탐 시 롤백하는 구조

| 플레이북 컴포넌트 | 핵심 역할 및 기능 | 주요 기술 및 규격 | 비고 |
|:---|:---|:---|:---|
| **트리거 (Trigger)** | 플레이북 실행 시작 조건 및 필터링 규칙 정의 | Webhook, SIEM Alert Ingestion | Initiation |
| **보강기 (Enrichment)** | IP, URL, 파일 해시를 CTI 및 사내 자산 정보와 교차 결합 | VirusTotal API, CMDB, Active Directory | Context |
| **분기 노드 (Branching)**| 조건식(If-Else) 및 스코어 기반 실행 경로 결정 | JSON Logic, Python Script | Decision |
| **인간 승인 노드** | 고위험 조치 전 담당자 승인 획득 (모바일 푸시/이메일) | Human-in-the-loop, Slack/Teams Bot | Safeguard |
| **액션 노드 (Action)** | 이기종 보안 장비에 차단, 격리, 패치 명령 전송 | OpenC2, REST API, SSH | Execution |
| **롤백 노드 (Rollback)** | 조치 실패 또는 오탐 발생 시 이전 구성으로 자동 복원 | Undo API, State Rollback Script | Recovery |

#### 한줄 요약
- 트리거, 컨텍스트 보강, 3단계 분기, 인간 승인 노드, 액션 및 롤백 엔진으로 구성된다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **SOAR 악성코드 대응 플레이북 5단계 실행 시퀀스**:
  1. EDR 악성코드 탐지 경보 트리거 발동
  2. CTI 평판 조회 및 호스트 자산 중요도 확인
  3. 자산 중요도에 따른 위험 등급 판별 및 승인 분기
  4. EDR 단말 네트워크 격리 및 방화벽 C2 IP 차단
  5. 롤백 검증, 사건 티켓 클로징 및 MTTR 지표 기록

</details>

```text
1. [경보 수신] EDR이 영업팀 PC에서 랜섬웨어 의심 파일 실행 경보 수신
            │
            ▼
2. [위협 보강 및 자산 확인]
    ├─ 파일 해시(SHA-256) CTI 조회 ➔ 악성 확진(위험도 98점)
    └─ [호스트 조회: 영업팀 일반 사용자 PC 확인 (비핵심 자산)]
            │
            ▼
3. [분기 로직 평가 (Branching)]
    ├─ 비핵심 자산 + 90점 이상 고신뢰 악성 ➔ [ 완전 자동화(Fully-Auto) 분기 선택 ]
    └─ (만약 금융 코어 서버였다면 관제 팀장 모바일 푸시 승인 분기로 진입)
            │
            ▼
4. [조치 실행 및 가역성 보장]
    ├─ EDR API 호출 ➔ 해당 단말 네트워크 실시간 격리 (관리망 통신만 유지)
    ├─ 차세대 방화벽 API 호출 ➔ C2 서버 통신 IP 차단 룰 추가
    └─ [API 응답 코드 200(성공) 수신 확인 ➔ 롤백 트리거 미발동]
            │
            ▼
5. [티켓 마감 및 감사 기록]
    ├─ 사건 처리 전 과정 타임라인 생성 ➔ MTTR 18초 기록
    └─ [ITSM 티켓 자동 생성 및 사용자 대상 조치 완료 알림 발송]
```

**동작 원리**

1. **자동화된 오탐 필터링**: CTI 점수와 내부 화이트리스트 대조를 통해 오탐 경보를 사전 선별
2. **동적 위험도 스케일링**: 경보 자체의 위험도와 대상 자산의 비즈니스 중요도를 곱하여 대응 수위 결정
3. **무중단 핀셋 통제**: 전체 네트워크를 차단하지 않고 감염된 호스트 1대만 격리하여 가용성 훼손 최소화
4. **가역적 안전망**: API 통신 타임아웃 또는 비정상 응답 발생 시 자동으로 이전 상태로 복구
5. **표준화된 MTTR 단축**: 수동 대응 시 평균 40분 소요되던 분석-차단 사이클을 30초 이내로 단축

#### 한줄 요약
- 경보 수신, 위협 보강, 3단계 분기, 조치 실행/롤백 검증, 티켓 마감 및 MTTR 기록 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **SOAR 3대 플레이북 실행 방식 비교**:
  - 완전 자동화 (Fully Automated): 사람 개입 없이 100% 기계가 차단 실행.
  - 인간 승인 기반 (Human-in-the-loop): 고영향 조치 전 팀장 승인 후 실행.
  - 수동 지원 (Manual Assisted): 보강 데이터만 제공하고 조치는 분석관이 직접 수동 수행.

</details>

| 비교 항목 | 완전 자동화 (Fully Automated) | 인간 승인 기반 (Human-in-the-loop) | 수동 지원 (Manual Assisted) |
|:---|:---|:---|:---|
| **적용 대상** | **단순 반복적 스팸/피싱, 명확한 악성 IP**| **대국민 웹서버, 코어 DB, 임원 단말 격리**| **고도화된 APT 공격, 신종 제로데이** |
| **대응 속도** | **수 초 ~ 수십 초 (최고 속도)** | 수 분 ~ 수십 분 (승인 대기 시간 소요) | 수 시간 (분석관 판단 소요) |
| **비즈니스 위험** | **오탐 시 정상 서비스 마비 리스크 존재** | **오탐 마비 위험 원천 차단 (가장 안전)** | 오탐 위험 없음 (인간 최종 확인) |
| **분석관 개입** | **0% (완전 무인화)** | **10% (단순 승인 버튼 클릭)** | 100% (심층 수동 분석) |
| **핵심 요구사항** | **철저한 오탐 검증 및 롤백 스크립트** | **모바일/메신저 승인 연동 워크플로우** | 풍부한 CTI 보강 데이터 대시보드 |

#### 한줄 요약
- 완전 자동화는 저위험 고속 처리, 인간 승인은 고위험 안전 처리, 수동 지원은 고난도 분석 지원이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **OASIS CACAO v2.0 (플레이북 표준 스키마) 및 OpenC2 (공통 명령 제어)**: 보안 오케스트레이션 플레이북의 상호운용성 및 기계 간 명령 표준 규격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SOAR 벤더(Splunk, Palo Alto 등) 교체 시 기존 구축된 수백 개의 독자 플레이북이 호환되지 않아 **전면 재개발 비용 및 운영 마비 발생** | **OASIS CACAO v2.0 국제 표준 스키마** 준수, **JSON 기반 표준 플레이북 포맷으로 워크플로우를 정의하여 벤더 독립성 확보** | 벤더 락인 0% 및 플레이북 재활용성 100% 보증 |
| 이기종 방화벽/EDR 장비마다 API 명령 포맷이 달라 **연동 스크립트 유지보수 복잡도 폭증 및 명령 누락 오류 발생** | **OASIS OpenC2 공통 전술 명령 프로토콜** 적용, **"Deny IP", "Isolate Host" 등 표준 명령어로 일원화하여 오케스트레이션 수행** | 이기종 장비 명령 호환성 100% 확보 및 개발 공수 대폭 절감 |
| 악성 IP 자동 차단 플레이북의 오탐으로 인해 **대국민 결제 게이트웨이(PG) 서버 IP가 차단되어 수십억 원의 결제 장애 손실 발생** | **핵심 비즈니스 서버 대상 Human-in-the-loop 승인 분기를 필수 강제하고, 오탐 시 즉각 복구하는 원클릭 롤백(Rollback) 파이프라인 구축** | 비즈니스 중단 사고 100% 예방 및 안전한 자동화 달성 |

#### 한줄 요약
- CACAO 표준으로 벤더 락인을 방지하고, OpenC2로 명령을 일원화하며, 인간 승인과 롤백으로 서비스 마비를 막는다.

## Ⅶ. 결론

- 현대 보안관제센터(SOC)의 대응 속도와 효율성을 혁신하는 핵심 중추인 **보안 오케스트레이션 플레이북 아키텍처**는 차세대 보안 운영의 필수 기반이며, 실무 구현 시 **OASIS CACAO 및 OpenC2 국제 표준 채택**, **위험도 기반 3단계 분기(완전 자동 / 인간 승인 / 수동)의 엄격한 설계**, **오탐 시 즉각 복구 가능한 가역적 롤백(Rollback) 메커니즘 구축**, **NIST SP 800-61 사고대응 생애주기와의 유기적 통합**을 완성하여 최고 수준의 관제 효율성과 비즈니스 안정성을 완성

#### 한줄 요약
- CACAO 표준 스키마와 위험 기반 인간 개입 분기 및 롤백 메커니즘을 통해 무결점 SOAR 플레이북을 완성한다.
