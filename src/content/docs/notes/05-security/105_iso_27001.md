## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **ISO(International Organization for Standardization)**: 국제 표준을 개발•발행하는 국제 기구.
- **IEC(International Electrotechnical Commission)**: 전기•전자 분야 국제 표준을 개발하는 협력 기구.
- **ISO/IEC 27001(Information Security Management System, ISO 27001)**: 정보보안 경영체계 요구사항을 규정한 국제 표준.
- **ISMS(Information Security Management System)**: 정보보안 위험과 통제를 지속적 경영 주기로 관리하는 체계.
- **위험 기반 통제(Risk-based Control)**: 자산, 위협, 영향 평가에 따라 보안 통제의 선택 및 제외 근거를 수립하는 방식.

</details>

- 정의/개념: **ISO**와 **IEC**가 제정한 **ISO/IEC 27001**은 **ISMS**의 **위험 기반 통제** 요구사항.
- 배경/필요성: 통제 목록만 일괄 적용하면 경영목표•위험과 보호조치 선택 근거를 연결하기 어려움.

#### 한줄 요약

- 위험을 평가해 통제를 선택하고 운영 결과를 계속 개선한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **SoA(Statement of Applicability, SoA)**: 통제 항목의 적용 및 제외 사유, 구현 상태를 명시한 선언서.
- **내부감사(Internal Audit)**: 관리체계의 적합성과 통제 효과성을 독립적으로 검증하는 평가 절차.
- **경영검토(Management Review)**: 경영진이 관리체계 성과, 자원 배분, 개선 방향을 의결하는 절차.

</details>

- 조직 상황과 이해관계자 요구로 ISMS 범위 설정.
- 위험평가•처리 결과를 **SoA**의 통제 적용•제외 근거에 연결.
- **내부감사**와 **경영검토**로 지속 개선 이행.

#### 한줄 요약

- SoA에 통제의 적용•제외 사유와 구현 상태를 기록한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **조직 상황(Context of the Organization)**: 이해관계자 요구사항 및 내부•외부 환경 이슈를 반영하는 프레임워크.
- **범위(Scope)**: ISMS가 적용되는 서비스, 조직, 정보 자산의 물리적•논리적 경계.
- **성과평가(Performance Evaluation)**: 보안 지표, 감사, 경영검토를 통해 관리체계 성과를 검증하는 활동.
- **시정조치(Corrective Action)**: 부적합 결함의 근본 원인을 분석하고 재발을 방지하는 보완 활동.

</details>

```text
ISO/IEC 27001 ISMS
├─ 조직 상황 · 범위
│  └─ 이해관계자 요구 · 적용 경계
├─ 리더십 · 계획
│  └─ 정책 · 역할 · 정보보호 목표
├─ 위험평가 · 처리
│  └─ 위험 기준 · 처리 계획
├─ SoA · 운영 통제
│  └─ 통제 선택 근거 · 운영 결과
└─ 성과평가 · 개선
   └─ 감사 · 경영검토 · 시정조치
```

| 구성요소 | 책임 |
|:---|:---|
| 조직 상황•범위 | **조직 상황**과 **범위** 설정 |
| 리더십•계획 | 정책•역할•정보보호 목표 승인 |
| 위험평가•처리 | 위험 기준•처리 계획 수립 |
| SoA•운영 통제 | **SoA**에 통제 선택 근거•운영 결과 기록 |
| 성과평가•개선 | **성과평가**•**경영검토**•**시정조치** 수행 |

#### 한줄 요약

- 범위와 목표를 정하고 위험에 맞는 통제를 운영•평가한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **Annex A(Annex A Control List)**: ISO 27001에 정의된 분야별 상세 정보보호 통제 항목 목록.
- **운영 증적(Operational Evidence)**: 보안 통제가 정상적으로 작동했음을 입증하는 로그, 문서, 승인 자료.
- **위험-SoA-운영 연결(Risk-SoA-Operation Mapping)**: 위험평가 결과, SoA의 통제 선택, 실제 운영 증적을 추적 가능하도록 연계하는 구조.
- **조직 상황•ISMS 범위 확정(Context and Scope Definition)**: 이해관계자 요구와 ISMS 적용 대상 경계를 수립하는 단계.
- **정보보안 위험 평가•처리(Security Risk Assessment and Treatment)**: 위험 평가 기준에 따라 보안 위험의 수준과 처리 방안을 확정하는 단계.
- **Annex A 통제•SoA 작성(Annex A Control and SoA Creation)**: 통제 항목별 적용•제외 사유와 이행 상태를 기록하는 단계.
- **통제 운영•증적 생성(Control Operation and Evidence Generation)**: 선택된 통제를 실행하고 관련 운영 기록을 생성하는 단계.
- **경영검토•시정안 수립(Management Review and Remediation Planning)**: 통제 효과성과 부적합 사항을 검토하여 개선안을 도출하는 단계.

</details>

```text
1. 조직 상황•ISMS 범위 확정
               │
               ▼
2. 정보보안 위험 평가•처리
               │
               ▼
3. Annex A 통제•SoA 작성
               │
               ▼
4. 통제 운영•증적 생성
               │
          감사 발견사항
               ▼
5. 경영검토•시정안 수립
               │
               └──── 개선안 ────┐
                                └─ 조직 상황 · 위험평가로 환류
```

### 동작 원리

1. **조직 상황·ISMS 범위 확정**: 경계·요구사항 확정
2. **정보보안 위험 평가·처리**: 우선순위·대응 결정
3. **Annex A 통제·SoA 작성**: 적용·제외 근거 기록
4. **통제 운영·증적 생성**: 운영 결과·증거 생성
5. **경영검토·시정안 수립**: 효과·부적합·개선안 결정

#### 한줄 요약

- SoA의 통제 선택 근거와 실제 운영 결과를 감사로 검증한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **ISO/IEC 27001:2022(ISMS Requirements, ISO 27001:2022)**: 정보보호 경영체계 수립 및 인증을 위한 국제 표준 규격.
- **ISO/IEC 27002:2022(Code of Practice for Information Security Controls, ISO 27002:2022)**: 세부 보안 통제의 실무적 구현 방법과 속성을 안내하는 지침.

</details>

| 표준 | 역할 | 연계 방식 |
|:---|:---|:---|
| **ISO/IEC 27001:2022** | 정보보호 관리체계 요구사항•인증 기준 | 위험 처리 결과에 따라 부속서 A 통제 선택 |
| **ISO/IEC 27002:2022** | 조직•인적•물리•기술 통제 구현 지침 | 선택한 통제의 목적•속성•구현 방법 보완 |

#### 한줄 요약

- 27001은 인증 요구사항, 27002는 통제 구현 지침이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **Amd 1:2024(Amendment 1:2024 Climate Action Changes)**: 조직 상황 분석 시 기후변화 요구사항을 추가 반영한 ISO 개정안.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISMS 인증 요구 | **ISO/IEC 27001:2022** 적용 | 위험 기반 운영 증명 |
| 통제 설계•구현 | **ISO/IEC 27002:2022** 참조 | 통제 구현 구체화 |
| 기후변화 관련성 | **Amd 1:2024** 검토 | **조직 상황** 누락 방지 |

#### 한줄 요약

- 외부 사업자와 데이터 흐름도 범위•위험평가•SoA에 연결한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **ISMS 운영 증명(ISMS Operational Demonstration)**: 위험에 맞춘 통제 이행 및 지속적 시정 이력을 설명 가능한 상태.

</details>

- 인증은 **27001**, 구현은 **27002**, 선택 근거는 **SoA** 적용

#### 한줄 요약

- 위험별 통제 선택 근거와 실제 운영 결과를 계속 증명한다.
