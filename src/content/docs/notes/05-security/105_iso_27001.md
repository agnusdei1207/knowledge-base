## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **ISO(International Organization for Standardization)**: 국제 표준을 개발•발행하는 기구이다.
- **IEC(International Electrotechnical Commission)**: 전기•전자 분야 국제 표준을 개발하는 기구이다.
- **ISO/IEC 27001**: 위험 기반 정보보안 경영체계의 인증 요구사항을 규정한 국제 표준이다.
- **ISMS(Information Security Management System)**: 정보보안 위험과 통제를 경영 주기로 관리하는 체계이다.
- **위험 기반 통제**: 통제 목록을 일괄 적용하지 않고 조직의 자산•위협•업무 영향을 평가한 결과로 선택•제외 근거를 정하는 방식이다.

</details>

- 정의/개념: **ISO**와 **IEC**가 제정한 **ISO/IEC 27001**은 **ISMS**의 **위험 기반 통제** 요구사항이다.
- 배경/필요성: 통제 목록만 일괄 적용하면 경영목표•위험과 보호조치 선택 근거를 연결하기 어렵다.

#### 한줄 요약

- 위험을 평가해 통제를 선택하고 운영 결과를 계속 개선한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **SoA(Statement of Applicability, 적용성 선언서)**: 각 정보보안 통제의 적용•제외 여부와 위험 처리 근거, 현재 구현 상태를 기록한 문서이다.
- **내부감사**: 통제 효과와 부적합을 독립적으로 점검하는 평가 절차이다.
- **경영검토**: 경영진이 목표•자원•시정•개선 방향을 결정하는 절차이다.

</details>

- 조직 상황과 이해관계자 요구로 ISMS 범위를 정한다.
- 위험평가•처리 결과를 **SoA**의 통제 적용•제외 근거에 연결한다.
- **내부감사**와 **경영검토**로 지속 개선한다.

#### 한줄 요약

- SoA에 통제의 적용•제외 사유와 구현 상태를 기록한다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **조직 상황**: 이해관계자 요구와 내부•외부 이슈를 분석한 경영 환경이다.
- **범위**: 서비스•조직•정보 경계를 반영해 정한 ISMS 적용 대상이다.
- **성과평가**: 지표•감사•경영검토로 통제 결과와 효과를 판단하는 활동이다.
- **시정조치**: 부적합의 근본 원인을 제거해 재발을 방지하는 활동이다.

</details>

```text
ISO/IEC 27001 ISMS
├─ 조직 상황 · 범위
│  └─ 이해관계자 요구 · 적용 경계
├─ 리더십 · 계획
│  └─ 정책 · 역할 · 정보보호 목표
├─ 위험평가 · 처리
│  └─ 위험 기준 · 처리 계획
├─ SoA · 운영 통제
│  └─ 통제 선택 근거 · 운영 결과
└─ 성과평가 · 개선
   └─ 감사 · 경영검토 · 시정조치
```

| 구성요소 | 책임 |
|:---|:---|
| 조직 상황•범위 | **조직 상황**과 **범위** 설정 |
| 리더십•계획 | 정책•역할•정보보호 목표 승인 |
| 위험평가•처리 | 위험 기준•처리 계획 수립 |
| SoA•운영 통제 | **SoA**에 통제 선택 근거•운영 결과 기록 |
| 성과평가•개선 | **성과평가**•**경영검토**•**시정조치** 수행 |

#### 한줄 요약

- 범위와 목표를 정하고 위험에 맞는 통제를 운영•평가한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **Annex A**: 위험 처리 때 선택 여부를 검토하는 정보보안 통제 목록이다.
- **운영 증적**: 선택한 통제가 실제 작동했음을 보여 주는 로그•승인•지표 자료이다.
- **위험-SoA-운영 연결**: 평가한 위험, 선택•제외한 통제 근거, 구현 상태와 결과를 일관되게 추적하는 구조이다.
- **조직 상황•ISMS 범위 확정**: 이해관계자 요구와 서비스•조직•정보 경계를 정하는 단계이다.
- **정보보안 위험 평가•처리**: 위험 기준에 따라 우선순위와 대응 방식을 결정하는 단계이다.
- **Annex A 통제•SoA 작성**: 통제별 적용•제외 근거와 구현 상태를 기록하는 단계이다.
- **통제 운영•증적 생성**: 선택한 통제를 수행하고 지표•로그•승인 기록을 만드는 단계이다.
- **경영검토•시정안 수립**: 통제 효과와 부적합을 검토해 개선안을 결정하는 단계이다.

</details>

```text
1. 조직 상황•ISMS 범위 확정
               │
               ▼
2. 정보보안 위험 평가•처리
               │
               ▼
3. Annex A 통제•SoA 작성
               │
               ▼
4. 통제 운영•증적 생성
               │
          감사 발견사항
               ▼
5. 경영검토•시정안 수립
               │
               └──── 개선안 ────┐
                                └─ 조직 상황 · 위험평가로 환류
```

### 동작 원리

1. **조직 상황•ISMS 범위 확정**: 이해관계자•경계•요구사항을 확정한다.
2. **정보보안 위험 평가•처리**: 위험 기준•우선순위•대응을 결정한다.
3. **Annex A 통제•SoA 작성**: **Annex A**의 적용•제외 근거와 상태를 기록한다.
4. **통제 운영•증적 생성**: **운영 증적**을 생성해 **위험-SoA-운영 연결**을 유지한다.
5. **경영검토•시정안 수립**: 통제 효과•부적합•개선안을 결정한다.

#### 한줄 요약

- SoA의 통제 선택 근거와 실제 운영 결과를 감사로 검증한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **ISO/IEC 27001:2022**: 정보보호 관리체계의 인증 요구사항을 규정한 국제 표준이다.
- **ISO/IEC 27002:2022**: 조직적•인적•물리적•기술적 정보보안 통제 구현 지침이다.

</details>

| 표준 | 역할 | 연계 방식 |
|:---|:---|:---|
| **ISO/IEC 27001:2022** | 정보보호 관리체계 요구사항•인증 기준 | 위험 처리 결과에 따라 부속서 A 통제 선택 |
| **ISO/IEC 27002:2022** | 조직•인적•물리•기술 통제 구현 지침 | 선택한 통제의 목적•속성•구현 방법 보완 |

#### 한줄 요약

- 27001은 인증 요구사항, 27002는 통제 구현 지침이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **Amd(Amendment) 1:2024**: 조직 상황과 이해관계자 요구에서 기후변화 관련성을 고려하도록 추가한 개정이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| ISMS 인증 요구 | **ISO/IEC 27001:2022** 적용 | 위험 기반 운영 증명 |
| 통제 설계•구현 | **ISO/IEC 27002:2022** 참조 | 통제 구현 구체화 |
| 기후변화 관련성 | **Amd 1:2024** 검토 | **조직 상황** 누락 방지 |

#### 한줄 요약

- 외부 사업자와 데이터 흐름도 범위•위험평가•SoA에 연결한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **ISMS 운영 증명**: 위험별 통제 선택 근거와 실제 수행 결과, 감사•경영검토•시정 이력을 계속 설명할 수 있는 상태이다.

</details>

- **ISMS 운영 증명**을 위해 인증은 **ISO/IEC 27001:2022**, 통제 구현은 **ISO/IEC 27002:2022**, 위험별 선택 근거는 **SoA**에 기록한다.

#### 한줄 요약

- 위험별 통제 선택 근거와 실제 운영 결과를 계속 증명한다.
