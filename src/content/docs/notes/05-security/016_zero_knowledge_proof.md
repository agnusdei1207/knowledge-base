## Ⅰ. 개요

<details>
<summary>용어 설명</summary>

- **영지식 증명(Zero-Knowledge Proof, ZKP)**: 비밀값을 공개하지 않고 정해진 관계가 성립한다는 사실만 증명하는 암호 프로토콜이다.
- **명제(Statement)**: 증명자가 참이라고 주장하고 검증자가 확인할 공개 주장이다.
- **비밀 증거(Witness)**: 외부에 공개하지 않지만 명제를 참으로 만드는 비밀 입력이다.

</details>

- 정의/개념: 비밀을 공개하지 않고 명제의 참만 입증하는 **영지식 증명(ZKP)**
- 배경/필요성: 원본 제출은 **사생활 침해•비밀 유출** 위험을 만든다.

#### 한줄 요약

- 비밀 데이터(Witness)의 직접 노출 없이 명제의 참 성립 여부만 증명하여 프라이버시 보호와 데이터 검증을 동시 달성

## Ⅱ. 특징

<details>
<summary>용어 설명</summary>

- **완전성(Completeness)**: 명제가 참이고 올바른 비밀 증거를 소유한 경우, 정직한 검증자는 이를 확률 1에 가깝게 참으로 승인하는 성질.
- **건전성(Soundness)**: 명제가 거짓인 경우, 부정직한 증명자가 검증자를 속여 거짓을 참으로 인정받을 수 없는 수학적 성질.
- **영지식성(Zero-knowledge)**: 명제가 참이라는 사실 외에 증명자의 원본 비밀 증거(Witness) 정보는 전혀 검증자에게 노출되지 않는 성질.
- **회로 크기(Circuit Size)**: 증명 대상 업무 논리를 불리언/산술 제약식으로 변환한 규모로, 크기에 비례해 증명 생성 시간과 검증 오버헤드 증가.

</details>

- **완전성**으로 정직한 참을 승인하고, **건전성**으로 거짓 증명자의 위변조 시도 원천 차단
- **영지식성**을 통한 원본 데이터 노출 제로화 달성
- 표현하려는 업무 논리의 **회로 크기** 및 연산 복잡도 관리가 핵심

#### 한줄 요약

- 수학적 3대 조건인 완전성(Completeness), 건전성(Soundness), 영지식성(Zero-knowledge) 만족 및 회로(Circuit) 오버헤드 통제

## Ⅲ. 구조 및 구성요소

<details>
<summary>용어 설명</summary>

- **관계(Relation)**: 공개 입력(Public Input)과 비밀 증거(Witness)가 성립해야 하는 수학적 조건식.
- **회로(Circuit)**: 검증하려는 업무 제약 논리를 덧셈과 곱셈 문(Gate)의 산술 회로(Arithmetic Circuit)로 표현한 데이터 구조.
- **증명자(Prover)**: 비밀 증거를 연산 회로에 적용하여 수학적 증명(Proof)을 발급하는 주체.
- **검증자(Verifier)**: 증명자가 전달한 증명 및 공개 입력을 바탕으로 명제의 참 여부를 최종 판단하는 주체.
- **공통 파라미터(Common Reference String, CRS)**: 증명 생성 및 검증에 공개적으로 활용되는 신뢰 설정 기반의 파라미터.

</details>

```text
영지식 증명 구조
├─ 공통 파라미터
├─ 증명자
├─ 검증자
├─ 비밀 증거
└─ 명제•관계 회로
```

가지의 의미: 환경 설정, 증명 생성, 유효성 검증, 비밀 입력 및 관계 회로 정의 책임을 분리한 구조

| 구성요소 | 책임 |
|:---|:---|
| 공통 파라미터 | **CRS 공개 설정값** 제공 |
| 증명자 | 비밀 증거로 **압축 증명** 생성 |
| 검증자 | **공개 입력•증명값**으로 승인 판정 |
| 비밀 증거 | 명제를 참으로 만드는 **비밀 입력** |
| 명제•관계 회로 | 업무 규칙을 **산술 제약식**으로 구조화 |


#### 한줄 요약

- 공통 파라미터, 증명자, 검증자, 비밀 증거(Witness) 및 관계 회로(Circuit)의 역할 분담 아키텍처

## Ⅳ. 흐름도

<details>
<summary>용어 설명</summary>

- **문맥 결합(Context Binding)**: 서비스 요청자 ID, 챌린지 난수, 세션 파라미터를 공개 입력에 바인딩하여 생성된 증명의 재사용(Replay)을 방지하는 기법.
- **증명 파라미터(Proving Key)**: 증명자가 연산 회로에 비밀 증거를 투입하여 증명을 생성할 때 사용하는 공개 파라미터.
- **검증 파라미터(Verification Key)**: 검증자가 작은 연산량으로 증명의 유효성을 판정할 수 있도록 제공하는 공개 검증키.
- **영지식 증명 생성**: 산술 회로 만족성을 입증하는 증명 패킷을 비공개로 생성하는 단계.
- **증명 유효성 검증**: 공개 검증키와 공개 입력을 통해 증명의 완전성과 건전성을 대조하는 단계.
- **회로•문맥•결과 판정**: 증명 유효성과 문맥 결합 정보를 종합 판단하여 승인하는 단계.

</details>

```text
공통 설정
        ├─ 1. 증명 파라미터 배포
        └─ 2. 검증 파라미터 배포
                    │
                    ▼
3. 영지식 증명 생성
        │
        └── 공개 입력•증명 전달
                    │
                    ▼
4. 증명 유효성 검증
        ├─ 실패: 증명 거부
        └─ 성공
             │
             ▼
     5. 회로•문맥•결과 판정
             ├─ 불일치: 업무 요청 거부
             └─ 일치: 검증 승인 반환
```

### 동작 원리

1. **증명 파라미터 배포**: 시스템 초기화 시 발급된 Proving Key 배포
2. **검증 파라미터 배포**: 검증 모듈 전용 Verification Key 배포
3. **영지식 증명 생성**: 증명자가 비밀 증거(Witness)와 회로를 결합하여 압축 증명 생성
4. **증명 유효성 검증**: 검증자가 공개 입력과 Verification Key 기반 수학적 완전성·건전성 판정
5. **회로•문맥•결과 판정**: 문맥 결합 정보(Nonce, Session) 검증 및 최종 비즈니스 승인 완료


#### 한줄 요약

- 공통 파라미터 배포, 증명자 생성, 검증자의 완전성·건전성 검증 및 문맥 바인딩 기반 재사용 차단

## Ⅴ. 종류 및 비교

<details>
<summary>용어 설명</summary>

- **zk-SNARK(Zero-Knowledge Succinct Non-Interactive Argument of Knowledge)**: 증명 크기가 수백 바이트로 매우 작고 검증 속도가 빠르나 초기 신뢰 설정(Trusted Setup)이 필요한 방식.
- **zk-STARK(Zero-Knowledge Scalable Transparent Argument of Knowledge)**: 신뢰 설정 없이 투명(Transparent)하며 양자 내성을 제공하지만 증명 크기가 상대적으로 큰 방식.
- **범위 증명(Range Proof)**: 비밀값의 구체적 수치는 숨긴 채 특정 수치 구간($a \le x \le b$) 내 존재함만 입증하는 특화 방식(Bulletproofs 등).

</details>

| 영지식 증명 방식 | **zk-SNARK** | **zk-STARK** | **범위 증명** |
|:---|:---|:---|:---|
| 적용 기준 | 증명 크기 최적화•블록체인 | 신뢰 설정 회피•양자 내성 요구 | 나이, 소득, 잔액 등 수치 범위 검증 |
| 핵심 특징 | 극소 크기 및 빠른 검증 속도 | 투명성(No Trusted Setup)•양자 내성 | 특정 범위 포섭 증명 특화 |
| 한계 | 신뢰 설정(CRS) 유출 위험 | 상대적으로 큰 증명 패킷 오버헤드 | 복잡한 일반 논리 표현 한계 |

> 요약: 신뢰 설정 필요 여부, 증명 크기 및 검증 대상 회로에 따른 프로토콜 선택

#### 한줄 요약

- 작은 증명은 **zk-SNARK**, 투명•양자 내성은 **zk-STARK** 선택

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>용어 설명</summary>

- **ISO/IEC 9798-5:2009(ISO/IEC 9798-5 Standard)**: 영지식 기법을 활용한 신원 인증 프로토콜 규정 국제 표준.
- **신뢰 설정(Trusted Setup)**: zk-SNARK에서 공통 파라미터 생성 시 사용된 무작위 파라미터(Toxic Waste)를 완전 파기해야 하는 절차.
- **현실 진실성(Reality Veracity)**: 회로에 투입되는 비밀 증거 자체가 정당한 발행기관(CA 등)에 의해 발급된 참된 데이터인지 입증하는 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 영지식 엔티티 인증 표준 미비 | **ISO/IEC 9798-5** 준수 | 신원 인증 절차 표준화 |
| 회로 결함 및 증명 재사용 | 회로 시큐어 코딩 및 **문맥 결합** | 위증 및 재생 공격(Replay) 차단 |
| 신뢰 설정 비밀(Toxic Waste) 유출 | 다자간 연산(MPC) 기반 **Trusted Setup** | 위조 증명 생성 위험 차단 |
| 비인가 허위 입력 투입 | **발행기관 디지털 서명** 결합 검증 | 허위 비밀 증거 투입 방지 |

#### 한줄 요약

- ISO/IEC 9798-5 준수, 신뢰 설정(Trusted Setup) 무결성 확보, 회로 미스매치 차단 및 외부 발급 서명 연동

## Ⅶ. 결론

<details>
<summary>용어 설명</summary>

- **영지식 증명 선택(ZKP Scheme Selection)**: 프라이버시 보호 수준, 증명 크기, 신뢰 설정 조건 및 연산 비용을 반영한 기술 채택 지침.

</details>

- **증명 방식 선택**에 따라 증명 크기 최적화는 **zk-SNARK**, 신뢰 설정 회피 및 양자 내성은 **zk-STARK** 적용

#### 한줄 요약

- **완전성•건전성•영지식성**과 **문맥 결합** 검증
