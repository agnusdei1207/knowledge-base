## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **영지식 증명(Zero-Knowledge Proof, ZKP)**: 증명자(Prover)가 검증자(Verifier)에게 자신이 특정 비밀 정보(Witness)를 알고 있다는 사실(명제)의 진위 외에는, 그 비밀 정보 자체에 관한 어떠한 추가 지식도 일절 노출하지 않고 참임을 수학적으로 증명하는 암호학적 대화/비대화 프로토콜.
- **비밀 증거(Witness)**: 증명자가 증명하고자 하는 연산 회로(Circuit)의 비공개 입력값(예: 비밀번호, 생년월일, 개인키, 금융 계좌 잔액).

</details>

- 정의/개념: 비공개 입력값(Witness)을 외부로 전송하지 않고 연산 제약식(R1CS / QAP) 만족 여부만을 증명하는 **비대화형 영지식 논증(NIZKP: zk-SNARKs / zk-STARKs)** 기반 **프라이버시 보존형 신원·상태 검증 아키텍처**
- 배경/필요성: 성인 인증이나 자격 증명 시 주민등록번호, 전체 계좌 내역 등 불필요한 민감 개인정보 원본이 검증자에게 과도하게 노출되어 발생하는 프라이버시 침해와 대규모 개인정보 유출 사고를 방지할 요구

#### 한줄 요약
- 원본 비밀 데이터를 전혀 공개하지 않고 명제의 참/거짓만을 수학적으로 검증한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **ZKP의 3대 필수 수학적 속성**:
  1. **완전성(Completeness)**: 명제가 참이고 증명자가 정직하다면, 검증자는 반드시 이를 참(True)으로 수락(Accept).
  2. **건전성(Soundness)**: 명제가 거짓이라면, 어떠한 부정직한 증명자도 검증자를 참으로 속일 수 있는 확률이 무시할 수 있을 만큼 극소($\epsilon \approx 0$).
  3. **영지식성(Zero-Knowledge)**: 검증자는 명제가 참이라는 사실 이외에 증명자의 비밀(Witness)에 대한 어떠한 정보도 얻을 수 없음.

</details>

- **데이터 주권 및 최소 정보 공개 (Selective Disclosure)**: 원본 데이터 대신 유효성 증명(Proof) 바이트열만 전송
- **비대화형 간결성 (Succinctness / zk-SNARKs)**: 수백만 게이트의 복잡한 연산 증명도 수백 바이트(약 128~256바이트)의 고정 크기 증명으로 압축되어 수 밀리초 내 검증 완료
- **블록체인 롤업(ZK-Rollup) 확장성**: 수천 건의 트랜잭션 연산을 오프체인에서 1개의 ZK Proof로 압축하여 메인넷 가스비와 블록 용량을 획기적으로 절감

#### 한줄 요약
- 완전성/건전성/영지식성 3대 속성 충족, 바이트 단위 초경량 간결성, 블록체인 및 DID 확장을 제공한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **산술 회로(Arithmetic Circuit) & R1CS(Rank-1 Constraint System)**: 검증하고자 하는 비즈니스 로직(예: $x \ge 19$)을 덧셈 및 곱셈 게이트의 다항식 제약식($A \cdot s \times B \cdot s - C \cdot s = 0$)으로 변환한 수학적 연산 모델.
- **공통 참조 문자열(Common Reference String, CRS)**: zk-SNARKs에서 증명 생성 키(Proving Key)와 검증 키(Verification Key)를 생성하기 위해 사전 합의되는 암호학적 파라미터.

</details>

```text
[ 비즈니스 요구사항 (예: 연령 19세 이상 증명) ]
                      │
                      ▼ (도메인 특화 언어: Circom / Noir 컴파일)
┌─────────────────────────────────────────────────────────────────────────┐
│ [ 산술 회로 및 R1CS 제약식 (Arithmetic Circuit: $A \cdot B = C$) ]        │
└────────────────────────────────────┬────────────────────────────────────┘
                                     │
                 ┌───────────────────┴───────────────────┐
                 ▼ (신뢰 설정: Trusted Setup)            ▼ (증명 생성)
┌──────────────────────────────────────┐┌──────────────────────────────────────┐
│ [ 공통 파라미터 (CRS 생성 모듈) ]     ││ [ 증명자 (Prover: 사용자 스마트폰) ]   │
│  ├─ 증명 키 ($pk$: Proving Key)      ││  ├─ 공개 입력 ($x$: 기준 연령 19)      │
│  └─ 검증 키 ($vk$: Verification Key) ││  ├─ 비밀 증거 ($w$: 실제 생년월일)     │
└──────────────────┬───────────────────┘│  └─ 타원곡선 페어링 기반 다항식 증명 $\pi$│
                   │                    └──────────────────┬───────────────────┘
                   │                                       │
                   │ (검증 키 $vk$ 제공)                   │ (공개 입력 $x$ + 증명 $\pi$ 전송)
                   ▼                                       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ [ 검증자 (Verifier: 서비스 서버 / 블록체인 스마트 컨트랙트) ]                 │
│  └─ 타원곡선 페어링 연산 ($e(\pi_A, \pi_B) \stackrel{?}{=} e(\alpha, \beta)$) ➔ [ Pass / Fail 판정 ]│
└──────────────────────────────────────────────────────────────────────────────┘
```

선의 의미: 산술 회로로부터 생성된 키를 바탕으로 증명자가 비밀 증거를 주입해 증명($\pi$)을 생성하고, 검증자가 비밀 노출 없이 수식 일치 여부를 판정하는 구조

| 구성요소 | 핵심 책임 및 역할 | 비고 |
|:---|:---|:---|
| **산술 회로 (Circuit)** | 검증 조건을 덧셈/곱셈 게이트 및 R1CS/QAP 다항식 행렬로 컴파일 변환 | Circom / Halo2 |
| **비밀 증거 (Witness)** | 사용자 로컬 기기에만 격리 보관되는 비공개 원본 데이터(비밀키, 주민번호) | Private Input |
| **증명자 (Prover)** | $pk$, 공개 입력 $x$, Witness $w$를 결합하여 압축된 영지식 증명($\pi$) 생성 | Prover Engine |
| **검증자 (Verifier)** | $vk$, 공개 입력 $x$, 증명 $\pi$를 입력받아 $O(1)$ 시간 내에 진위 여부 검증 | Verifier Contract |
| **신뢰 설정 (Trusted Setup)**| MPC(다자간 연산)를 통해 CRS를 안전하게 생성하고 독성 폐기물(Toxic Waste) 소거 | Powers of Tau |

#### 한줄 요약
- 산술 회로, 비밀 증거(Witness), 증명자(Prover), 검증자(Verifier), 신뢰 설정(CRS)이 결합한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **피아트-샤미르 변환(Fiat-Shamir Heuristic)**: 상호 대화형(Interactive) 영지식 증명에서 검증자가 던지는 무작위 챌린지(Challenge)를 암호학적 해시 함수($\text{Hash}(\text{Commitment})$)로 대체하여, 단 1회의 메시지 전송으로 완결되는 비대화형(Non-Interactive) 증명으로 변환하는 암호 기법.

</details>

```text
1. 시스템 초기화 시 산술 회로를 컴파일하고 MPC 다자간 연산으로 증명 키($pk$)와 검증 키($vk$) 배포
            │
            ▼
2. 사용자가 스마트폰 로컬 환경에서 비밀 증거($w$: 실제 소득 증명)를 회로에 주입하여 Witness 생성
            │
            ▼
3. Prover 엔진이 피아트-샤미르 변환을 적용하여 비대화형 증명값($\pi$, 약 256바이트) 계산
            │
            ▼
4. 클라이언트가 검증자 서버로 [공개 조건($x$: 소득 5천만원 이상) + 증명값($\pi$)] 전송 (원본 $w$ 미전송)
            │
            ▼
5. 검증자가 $vk$를 사용하여 타원곡선 페어링 수학 연산 검증 ➔ 3ms 내에 참/거짓 판정 완료
```

**동작 원리**

1. **회로 컴파일**: 검증 조건($f(x, w) = 1$)을 QAP(Quadratic Arithmetic Program) 다항식으로 변환
2. **비밀 주입**: 증명자 메모리 내에서만 Witness $w$를 대입하여 유효한 다항식 해(Solution) 구성
3. **영지식 블라인딩**: 무작위 난수($r$)를 주입하여 다항식 계수를 마스킹함으로써 정보 누설 차단
4. **증명 압축**: 타원곡선 점 곱셈(MSM: Multi-Scalar Multiplication)으로 수백 바이트 증명 $\pi$ 추출
5. **결정론적 검증**: 쌍선형 페어링(Bilinear Pairing) 등식 성립 여부만 확인하여 즉시 인가

#### 한줄 요약
- 회로 컴파일, 로컬 Witness 주입, 비대화형 증명 생성, 공개 입력/증명 전송, 페어링 검증 판정 순으로 동작한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **zk-SNARKs vs zk-STARKs vs Bulletproofs**: 신뢰 설정 필요성, 증명 크기, 양자내성 여부에 따른 영지식 증명 스킴 비교.

</details>

| 비교 항목 | zk-SNARKs (Groth16 / Plonk) | zk-STARKs (StarkNet 표준) | Bulletproofs (범위 증명 전용) |
|:---|:---|:---|:---|
| **수학적 기반** | **타원곡선 페어링 (KZG 다항식)** | **해시 함수 + FRI (Reed-Solomon)** | **타원곡선 이산대수 (IPA)** |
| **신뢰 설정 (Trusted Setup)**| **필수 (MPC 세레모니 필요)** | **불필요 (완전 투명성: Transparent)**| **불필요 (Transparent)** |
| **증명 크기 (Proof Size)** | **초경량 ($\approx 128 \sim 256\text{ Bytes}$)**| **큼 ($\approx 40 \sim 100\text{ KB}$)** | 중간 ($\approx 1 \sim 2\text{ KB}$) |
| **검증 속도** | **극도로 빠름 ($\approx 2 \sim 5\text{ms}$)** | 빠름 ($\approx 10 \sim 20\text{ms}$) | 느림 (연산 수에 선형 비례) |
| **양자 공격 저항성** | **취약 (타원곡선 이산대수 기반)** | **영구적 안전 (해시 함수 기반 PQC)**| 취약 |
| **주요 적용 영역** | **ZK-Rollup, 프라이버시 코인(Zcash)** | **대규모 블록체인(Starknet), L2 롤업**| **모네로(Monero), 금융 잔액 범위 증명**|

#### 한줄 요약
- zk-SNARKs는 초소형 크기와 초고속 검증 표준, zk-STARKs는 신뢰 설정이 없고 양자 안전한 차세대 표준이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **독성 폐기물(Toxic Waste)**: zk-SNARKs 신뢰 설정(Trusted Setup) 시 생성되는 임의의 비밀 난수($\alpha, \beta, \gamma, \delta$)로, 이 값이 영구 폐기되지 않고 유출될 경우 공격자가 거짓 명제에 대해서도 유효한 가짜 증명(Fake Proof)을 무제한 위조할 수 있는 보안 취약점.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| zk-SNARKs 신뢰 설정 시 생성된 난수(Toxic Waste) 유출로 인한 **가짜 증명 무한 위조 사고** | **수천 명이 참여하는 MPC(다자간 연산) 세레모니(Powers of Tau) 적용 또는 STARK 전환** | 1명만 정직해도 비밀 복구 불가능 보증 및 위조 증명 원천 차단 |
| 공격자가 정상 증명값($\pi$)을 스니핑하여 다른 세션/트랜잭션에 재전송하는 **Replay 공격** | **공개 입력($x$)에 세션 난수(Nonce), 타임스탬프, 수신자 FQDN을 바인딩** 강제 | 증명의 유효 컨텍스트 고정 및 재전송 공격 100% 차단 |
| 증명자가 위조/조작된 가짜 신분증 데이터를 Witness로 주입하여 **합법적 자격을 획득하는 위장** | 산술 회로 내부에서 **공인 인증기관(CA/정부)의 전자서명 검증 로직을 제약식으로 결합** | 위조된 가짜 데이터 투입 방어 및 증명 진본성 무결점 확보 |

#### 한줄 요약
- MPC 세레모니로 Toxic Waste를 소거하고, Nonce 바인딩으로 Replay를 막으며, 서명 검증 회로로 데이터 진본성을 보증한다.

## Ⅶ. 결론

- 데이터 활용과 개인정보 보호라는 상충된 요구를 수학적으로 완벽히 해결하는 **영지식 증명(ZKP) 아키텍처**는 차세대 분산 신원 증명(DID), 블록체인 ZK-Rollup, AI 모델 소유권 검증의 핵심 기반 기술이며, 실무 구현 시 **zk-SNARKs와 zk-STARKs의 요구조건별 최적 선정**, **MPC 기반 안전한 신뢰 설정(Trusted Setup) 거버넌스**, **컨텍스트 바인딩 및 서명 검증 회로 결합**을 통합 구현하여 완결성 높은 프라이버시 보존형 신뢰 인프라를 완성

#### 한줄 요약
- 완전성/건전성/영지식성 3대 속성과 비대화형 SNARK/STARK 기술을 통해 데이터 노출 없는 무결점 자격 검증을 실현한다.
