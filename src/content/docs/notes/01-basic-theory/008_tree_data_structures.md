## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **균형 탐색 트리(Balanced Search Tree)**: 키 순서 조건과 균형 규칙으로 높이를 제한한 계열이며 B-Tree•AVL•레드블랙 트리를 포함한다.
- **편향 트리(Skewed Tree)**: 한쪽 자식만 이어져 선형화된 트리이다.

</details>

- 정의/개념: 키 순서 조건과 각 방식의 균형 규칙으로 높이를 제한하는 **균형 탐색 트리** 계열이다.
- 배경/필요성: 단순 이진 탐색 트리는 입력 순서에 따라 한쪽으로 편향되어 탐색 비용이 선형으로 악화될 수 있다.

#### 한줄 요약

- 노드 키 기준 서브트리 분할을 통해 탐색 공간을 제한하고, 트리 편향 방지를 위해 회전 및 재균형을 수행한다.


## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로그 시간 $O(\log n)$**: 입력이 늘어도 처리 단계가 완만하게 증가하는 시간 상한이다.
- **균형 유지**: 한쪽 경로가 지나치게 길어지지 않도록 트리 높이를 제한하는 작업이다.
- **범위 탐색**: 키 순서를 이용해 일정 구간에 속하는 원소를 차례로 찾는 탐색이다.
- **키 순서 조건**: 노드의 키를 기준으로 자식별 키 범위를 구분해 탐색 방향을 정하는 규칙이다.

</details>

![AVL과 레드블랙 트리의 키 수별 높이 상한](/study/diagrams/balanced-tree-height.svg)

> 키 수가 늘어도 두 선은 로그 증가하며 파란 AVL 높이 상한이 붉은 레드블랙보다 낮고, 각 균형 규칙의 이론적 상한이다.

- **키 순서 조건**으로 탐색 범위를 계층적으로 축소한다.
- **균형 유지**로 탐색•삽입•삭제의 $O(\log n)$ 보장이 핵심이다.
- 키 순서를 보존한 **범위 탐색**을 지원한다.

#### 한줄 요약

- 트리 노드의 삽입/삭제 시 발생한 높이 불균형을 트리 회전(Rotation) 및 색상 재지정(Recoloring) 연산으로 정정하여 최악 점근 높이를 $O(\log N)$으로 제어한다.



## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트(Root)**: 트리 탐색을 시작하는 최상위 노드이다.
- **균형 정보**: 높이 차나 색상처럼 트리의 균형 규칙을 판정하는 노드 상태이다.
- **회전(Rotation)**: 키 순서를 보존하며 부모•자식 관계를 바꿔 균형을 복구하는 연산이다.
- **색상 규칙**: 레드블랙 트리가 노드 색상과 루트부터 리프까지의 조건으로 높이를 제한하는 규칙이다.
- **분할(Split)**: B-Tree의 가득 찬 노드를 나누고 중앙 키를 부모로 올리는 연산이다.
- **탐색 경로**: 루트부터 목표 키나 삽입 위치까지 키 비교로 선택한 노드의 순서이다.
- **색상 변경**: 레드블랙 트리의 경로 조건을 회복하도록 노드 색을 다시 지정하는 작업이다.

</details>

```text
균형 탐색 트리 구조
├─ 루트 참조
├─ 탐색 제어기
├─ 트리 노드
└─ 균형 복구기
```

가지의 의미: 시작점•탐색•저장•균형 복구의 정적 책임 분리를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 루트 참조 | **루트**의 탐색 시작 위치 보관 |
| 탐색 제어기 | 키 대소로 **탐색 경로** 선택 |
| 트리 노드 | 키•자식 참조와 **균형 정보** 보관 |
| 균형 복구기 | **회전•색상 변경•분할**로 규칙 복구 |

#### 한줄 요약

- 탐색 제어기가 루트부터 키를 비교하고, 균형 복구기가 갱신된 노드의 규칙 위반을 바로잡는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **균형 규칙 위반**: 갱신으로 높이 차•색상•노드 키 수 조건을 벗어난 상태이다.

</details>

```text
키 처리 요청
   │
   ▼
1. 키 비교•자식 선택
   ├─ 목표 미도달: 자식에서 반복
   └─ 목표•삽입 위치 도달
      ├─ 조회: 처리 결과 반환
      └─ 갱신
         │
         ▼
2. 균형 규칙 판정
├─ 충족: 처리 결과 반환
└─ 위반
   │
   ▼
3. 균형 복구
   │
   ▼
처리 결과 반환
```

**동작 원리**

1. **키 비교•자식 선택**: 루트부터 키의 대소 관계를 비교하여 목표가 있을 수 있는 자식 경로를 선택한다.
2. **균형 규칙 판정**: 삽입•삭제 경로에서 높이 차, 색상 또는 노드 키 수가 해당 트리의 규칙을 위반하는지 확인한다.
3. **균형 복구**: 위반이 있으면 회전, 색상 변경 또는 노드 분할•병합으로 높이 제한을 회복한다.

#### 한줄 요약

- 키 비교로 목표 경로를 찾고, 규칙 위반 시 회전·색상 변경·분할로 높이를 제한한다.



## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **B-Tree**: 한 노드에 여러 키와 자식을 저장해 저장장치 페이지 접근 횟수를 줄이는 균형 트리이다.
- **AVL 트리(Adelson-Velsky and Landis Tree, AVL)**: 좌우 서브트리 높이 차를 1 이하로 유지하는 이진 탐색 트리이다.
- **레드블랙 트리(Red-Black Tree)**: 노드 색상과 경로 규칙으로 높이를 제한하는 이진 탐색 트리이다.
- **다진 분기(Multiway Branching)**: 한 노드가 셋 이상의 자식을 가져 트리 높이를 줄이는 구조이다.
- **페이지(Page)**: 외부 저장소에서 한 번에 읽고 쓰는 데이터 블록이다.
- **재균형(Rebalancing)**: 삽입이나 삭제 뒤 트리의 높이 제한 규칙을 다시 만족시키는 작업이다.
- **균형 강도**: 허용하는 경로 길이 차이의 엄격함을 나타내며 탐색 길이와 갱신 비용을 좌우하는 정도이다.
- **조회 중심**: 탐색 빈도가 삽입•삭제 빈도보다 높은 워크로드이다.
- **갱신 중심**: 삽입•삭제 빈도가 탐색 빈도보다 높은 워크로드이다.

</details>

| 균형 탐색 트리 | B-Tree 계열 | AVL 트리 | 레드블랙 트리 |
|:---|:---|:---|:---|
| 적용 기준 | **페이지 단위** 외부 저장소 색인 | 갱신이 드문 **조회 중심** | 삽입•삭제가 잦은 **갱신 중심** |
| 핵심 특징 | **다진 분기**로 노드당 여러 키 보유 | 좌우 **높이 차 1 이하** 제한 | 노드 **색상•경로 규칙** 유지 |
| 한계 | 분할•병합 시 **페이지** 쓰기 비용 | 삭제 시 상향 **재균형** 반복 | AVL보다 긴 **탐색 경로** |

> 요약: 노드당 키 수•**균형 강도**에 따른 갱신 비용 차이 핵심이다.

#### 한줄 요약

- 디스크 I/O 최적화를 위해 다진(Multi-way) B-Tree를 적용하고, 메인 메모리 환경에서는 조회/갱신 비중에 따라 AVL 또는 Red-Black 트리를 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **B-Tree 차수(Order)**: 한 노드가 가질 수 있는 자식 수의 상한이다.
- **복구 로그(Recovery Log)**: 장애 복구를 위해 변경 이력을 기록하는 로그이다.
- **원자적 쓰기(Atomic Write)**: 변경을 전부 반영하거나 전혀 반영하지 않는 쓰기이다.
- **잠금 경합(Lock Contention)**: 여러 실행 흐름이 같은 노드 잠금을 얻으려고 대기하는 상태이다.
- **워크로드(Workload)**: 시스템에서 조회•삽입•삭제가 발생하는 빈도와 비율이다.
- **교착(Deadlock)**: 실행 흐름들이 서로 가진 잠금을 기다려 모두 진행하지 못하는 상태이다.
- **입출력(Input/Output, I/O)**: 저장소 페이지와 메모리 사이의 읽기•쓰기 작업이다.
- **구조 일관성**: 복구 뒤 모든 키 경로와 균형 규칙이 함께 유효한 상태이다.
- **잠금 순서**: 동시 갱신이 여러 노드 잠금을 항상 같은 방향과 순서로 획득하는 규칙이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 낮은 **B-Tree 차수**로 트리 높이와 I/O 증가 | 페이지 크기에 맞춘 B-Tree 차수 설정 | 트리 높이와 **I/O** 감소 |
| **워크로드**와 균형 정책 불일치로 비용 증가 | 조회 중심 AVL, 갱신 중심 레드블랙 선택 | 탐색•회전 비용의 균형 확보 |
| 분할•병합 중 장애로 일부 구조만 반영돼 경로 손상 | **복구 로그•원자적 쓰기** 적용 | 장애 후 **구조 일관성** 복구 |
| 동시 노드 갱신의 **잠금 경합** | 루트•리프 방향 **잠금 순서**와 범위 고정 | **교착** 방지와 동시 처리량 안정화 |

#### 한줄 요약

- 디스크 블록/페이지 크기와 노드 Fan-out을 정렬하여 트리 높이 및 페이지 I/O 발생 빈도를 최소화한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **선택 기준**: 저장 매체와 조회•갱신 비율에 따라 균형 트리 종류를 고르는 판단 기준이다.

</details>

- **선택 기준**은 외부 저장소면 B-Tree, 메모리 조회 중심이면 AVL, 갱신 중심이면 레드블랙이다.

#### 한줄 요약

- 외부 저장소는 B-Tree, 메모리 조회 중심은 AVL, 갱신 중심은 레드블랙을 선택한다.
