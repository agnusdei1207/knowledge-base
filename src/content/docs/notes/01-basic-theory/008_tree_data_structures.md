## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **키 정렬 규칙(Key Ordering Rule)**: 부모 노드의 키를 기준으로 좌측 서브트리에는 더 작은 키, 우측 서브트리에는 더 큰 키를 배치하는 이진 탐색 불변식.
- **탐색 공간(Search Space)**: 목표 키를 찾기 위해 거쳐야 하는 전체 후보 노드들의 집합.
- **편향(Skewed)**: 데이터가 정렬된 순서대로 삽입되어 트리가 한쪽 자식 노드로만 길게 늘어져 선형 연결 리스트($O(n)$)로 퇴화하는 문제.

</details>

- 정의/개념: 노드 간 계층 관계와 **키 정렬 규칙**에 기반해 분기하여 데이터 **탐색 공간**을 축소하는 비선형 자료구조
- 배경/필요성: 단순 이진 탐색 트리(BST)에서 정렬된 데이터 입력 시 한쪽으로 **편향**되어 검색 시간이 선형($O(n)$)으로 퇴화하는 트리 불균형 한계

#### 한줄 요약

- 키로 탐색 공간을 줄이고 재균형으로 트리 편향을 방지한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로그 시간 $O(\log n)$**: 데이터 규모가 급증해도 연산 단계가 완만하게 증가하는 최적의 시간 상한.
- **균형 유지(Balancing Maintenance)**: 삽입·삭제 후에도 특정 경로가 길어지지 않도록 높이 불변식을 복구하는 작업.
- **범위 탐색(Range Search)**: 키 정렬 순서를 활용하여 특정 구간의 원소들을 연속 추출하는 기능.
- **중위 순회(In-Order Traversal)**: 왼쪽 서브트리, 루트 노드, 오른쪽 서브트리 순으로 방문하여 키를 오름차순으로 추출하는 트리 순회 방식.

</details>

![AVL과 레드블랙 트리의 키 수별 높이 상한](/study/diagrams/balanced-tree-height.svg)

> 키 수가 늘어도 두 선은 로그 증가하며 파란 AVL 높이 상한이 붉은 레드블랙보다 낮고, 각 균형 규칙의 이론적 상한임

- **키 정렬 규칙** 기반 계층적 분기 분할을 통한 탐색 공간 축소
- **균형 유지**를 통한 탐색·삽입·삭제 연산의 **로그 시간** $O(\log n)$ 보장
- 키 정렬 순서를 보존한 **범위 탐색** 및 **중위 순회** 지원

#### 한줄 요약

- 삽입·삭제 후 균형을 복구하여 높이를 $O(\log N)$으로 제한한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트(Root)**: 트리 탐색의 시작점이 되는 최상위 진입 노드.
- **균형 정보(Balance Metadata)**: 높이·색상·키 수처럼 트리 균형 규칙 판정에 사용하는 노드 메타데이터.

</details>

```text
[균형 탐색 트리 아키텍처]
  │
  ├─ [루트 노드 (Root)] (계층 탐색 최상위 진입점)
  │
  └─ [트리 서브시스템]
        ├─ [키·데이터 필드] (정렬 순서 키 및 페이로드)
        ├─ [균형 메타데이터] (높이차·노드 색상·차수 정보)
        └─ [분기 포인터] (좌우 자식 또는 다자식 링크)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 루트 참조 | 전체 트리의 탐색 시작 위치를 보관하는 **루트** 참조 |
| 트리 노드 | 키·데이터와 하위 노드의 자식 포인터 보관 |
| 균형 정보 | 노드별 **균형 정보**로 규칙 위반 판정 |

#### 한줄 요약

- 노드의 키와 자식 포인터로 탐색하고 균형 정보로 규칙 위반을 판정한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **균형 규칙 판정**: 노드 삽입/삭제 후 서브트리 높이 차, 레드-블랙 색상 조건, B-Tree 차수 조건 위반 여부를 검사하는 절차.
- **균형 복구(Rebalancing)**: 단일/이중 회전, 색상 반전, 노드 분할·병합을 통해 트리의 $O(\log n)$ 높이 상한을 회복하는 연산.
- **회전(Rotation)**: 이진 탐색 트리의 정렬 순서를 보존하면서 부모-자식 간 포인터 링크를 재배치하여 서브트리 높이를 축소하는 연산.
- **색상 규칙(Color Invariants)**: 레드블랙 트리에서 루트-리프 간 블랙 노드 수 동일 유지 및 연속 레드 노드 금지를 규정하는 불변식.
- **노드 분할(Node Split)**: B-Tree에서 노드가 가득 찼을 때 중간 키를 부모 노드로 승격시키고 노드를 2개로 분리하는 연산.

</details>

```text
[트리 키 검색 및 갱신(삽입/삭제) 요청]
                    │
                    ▼
[1. 루트로부터 대소 비교 기반 하향식 자식 탐색]
                    │
                    ▼
          <목표 위치 도달 여부 판정>
                    │
          ┌─────────┴─────────┐
          │                   │
      [단순 조회]          [갱신(삽입/삭제)]
          │                   │
          ▼                   ▼
    [데이터 반환]      [2. 노드 데이터 갱신 및 링크 재구성]
                              │
                              ▼
                     <균형 불변식 위반 판정>
                              │
                    ┌─────────┴─────────┐
                    │                   │
               [규칙 충족]           [규칙 위반]
                    │                   │
                    │                   ▼
                    │          [3. 균형 복구 연산 실행]
                    │          - AVL: 단일/이중 회전
                    │          - Red-Black: 색상 반전/회전
                    │          - B-Tree: 노드 분할/병합
                    │                   │
                    ▼                   ▼
[4. 트리의 O(log n) 높이 불변식 복원 및 트랜잭션 완료]
```

분기 결과: 단순 조회는 키 비교 경로를 따라 하향 이동하여 즉시 반환되며, 삽입·삭제 갱신 시 균형 규칙 위반이 발생하면 회전, 색상 반전, 노드 분할 등의 복구 연산을 통해 트리의 $O(\log n)$ 높이 상한을 복원함

**동작 원리**:
1. 루트 노드에서 시작하여 탐색 키와 노드 키 간의 대소 관계를 비교하며 하위 자식 노드로 순차 이동함.
2. 목표 리프 위치에 도달하면 신규 노드를 삽입하거나 대상 노드를 삭제하여 데이터베이스 링크를 갱신함.
3. 갱신 경로를 따라 상향 역추적하며 AVL 높이 차, 레드블랙 색상 조건, 또는 B-Tree 차수 충족 여부를 검사함.
4. 균형 조건 위반 감지 시 트리 **회전(Rotation)**, **색상 규칙**에 따른 색상 반전, 또는 **노드 분할(Node Split)**과 병합을 국소적으로 수행함.
5. 루트까지의 모든 서브트리 균형을 맞춰 최악의 경우에도 $O(\log n)$ 탐색 시간이 보장되는 정규 상태를 완성함.

#### 한줄 요약

- 키 비교로 목표 경로를 찾고, 규칙 위반 시 회전·색상 변경·분할로 높이를 제한한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **B-Tree**: 노드당 다수의 키와 자식 포인터를 배치하여 트리 높이를 극소화하고 디스크 I/O를 절감하는 다진 균형 트리.
- **AVL 트리**: 좌우 서브트리의 높이 차(Balance Factor)를 항상 1 이하로 엄격히 유지하는 이진 탐색 트리.
- **레드블랙 트리(Red-Black Tree)**: 노드에 블랙/레드 색상을 부여하고 경로별 블랙 높이를 일치시켜 높이를 $2\log(n+1)$ 이하로 유지하는 트리.

</details>

| 트리 구조 | B-Tree/B+Tree 계열 | AVL 트리 | 레드블랙 트리 (Red-Black Tree) |
|:---|:---|:---|:---|
| 적용 기준 | 페이지 단위 디스크 I/O 절감 및 대용량 DB 인덱스 구축 시 | 삽입/삭제가 드물고 읽기 조회가 지배적인 인메모리 환경 시 | 삽입·삭제가 빈번하여 균형 복구 회전 비용을 최소화해야 하는 환경 시 |
| 핵심 특징 | 다진 분기 및 높은 Fan-out | 좌우 높이 차 1 이하 엄격한 균형 | 노드 색상 및 블랙 경로 규칙 유지 |
| 한계 | 분할·병합 시 추가적인 디스크 I/O 발생 | 삽입·삭제 시 엄격한 트리 회전 오버헤드 | AVL 대비 다소 높은 트리 높이 |

#### 한줄 요약

- 디스크 인덱스는 B-Tree 계열, 조회는 AVL, 갱신은 레드블랙을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **B-Tree 차수(Order)**: 한 노드가 가질 수 있는 최대 자식 노드 수(Fan-out)로, 차수가 클수록 전체 트리 높이가 낮아짐.
- **로그 선행 기입(Write-Ahead Logging, WAL)**: 트리의 노드 분할·병합 등 변경 사항을 데이터베이스 페이지에 반영하기 전에 영속 로그에 먼저 기록하는 기법.
- **잠금 커플링(Lock Coupling, Lock Crabbing)**: 트리 동시성 제어 시 부모 노드의 잠금을 획득한 후 자식 노드 잠금을 얻고 부모 잠금을 해제하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 낮은 **B-Tree 차수**로 인한 트리 높이 및 디스크 I/O 증가 | 블록/페이지 크기(4KB/8KB)에 맞춘 차수 확장 | 트리 높이 축소 및 디스크 I/O 절감 |
| 워크로드와 균형 정책 불일치로 회전 오버헤드 증가 | 조회 중심 AVL, 갱신 중심 레드블랙 선택 | 탐색과 갱신 비용 간 최적 균형 확보 |
| 노드 분할·병합 중 장애로 인한 트리 경로 손상 | **로그 선행 기입(WAL)** 기반 원자적 연산 적용 | 장애 발생 시 구조 일관성 보장 |
| 동시 노드 갱신에 따른 잠금 경합 및 교착상태 발생 | 하향식 **잠금 커플링** 적용 | 동시성 향상 및 교착상태 방지 |

#### 한줄 요약

- B-Tree 차수를 페이지 크기에 맞춰 I/O를 줄이고, 조회 중심이면 AVL·갱신 중심이면 레드블랙을 선택하며, 분할·병합 장애는 WAL로, 동시 갱신은 Lock Crabbing으로 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **비트리 플러스(B+Tree)**: 모든 실제 레코드 포인터를 리프 노드에만 보관하고 리프 간 연결 리스트를 구성하여 순차 범위 검색 성능을 극대화한 다진 균형 트리.
- **관계형 데이터베이스 관리 시스템(Relational Database Management System, RDBMS)**: 테이블 기반 관계 모델로 데이터를 구조화하고 트랜잭션 원자성을 보장하는 소프트웨어 시스템.
- **비휘발성 메모리 익스프레스 솔리드 스테이트 드라이브(Non-Volatile Memory Express Solid State Drive, NVMe SSD)**: PCIe 고속 버스를 직접 활용하여 초고속 대규모 병렬 입출력을 지원하는 차세대 비휘발성 플래시 저장 매체.
- **로그 구조화 병합 트리(Log-Structured Merge-Tree, LSM-Tree)**: 쓰기를 메모리 버퍼에 순차 기록한 후 디스크에 단계별 정렬 파일로 플러시하여 랜덤 쓰기 증폭을 억제하는 트리 구조.

</details>

- **RDBMS**의 **B+Tree**와 커널 스케줄러의 레드블랙 트리가 표준으로 안착되었으며, 초고속 **NVMe SSD** 및 분산 환경에서는 쓰기 부하를 흡수하는 **LSM-Tree**와 학습형 인덱스로 진화 추세.
- 논리적 탐색 복잡도를 넘어 스토리지 블록 크기, 쓰기 증폭 계수 및 재균형 오버헤드를 정량 분석한 인덱스 아키텍처 결단 필요.

#### 한줄 요약

- LSM-Tree와 학습형 인덱스로 다변화되는 트리 진화에 맞추어 스토리지 매체 특성과 읽기·쓰기 비율에 최적화된 인덱스 아키텍처 확보 필요.
