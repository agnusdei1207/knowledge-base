## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **균형 탐색 트리(Balanced Search Tree)**: 키 순서 조건과 균형 규칙을 적용하여 트리 높이를 $O(\log n)$으로 제한하는 트리 구조 계열.
- **편향 트리(Skewed Tree)**: 데이터가 정렬 순서대로 삽입되어 한쪽 자식으로만 치우쳐 선형 리스트 형태로 퇴화한 트리.

</details>

- 정의/개념: 키 순서 조건과 각 방식의 고유 균형 규칙으로 트리의 최대 높이를 $O(\log n)$으로 제한하는 **균형 탐색 트리 계열**
- 배경/필요성: 단순 이진 탐색 트리는 입력 순서에 따라 한쪽으로 편향되어 탐색 비용이 $O(n)$으로 악화되므로 **엄격한 $O(\log n)$ 높이 제한 및 재균형 메커니즘 필수**

#### 한줄 요약

- 노드 키 기준 서브트리 분할을 통해 탐색 공간을 제한하고, 트리 편향 방지를 위해 회전 및 재균형을 수행

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **로그 시간 $O(\log n)$**: 데이터 규모가 급증해도 연산 단계가 완만하게 증가하는 최적의 시간 상한.
- **균형 유지(Balancing Maintenance)**: 삽입·삭제 후에도 특정 경로가 길어지지 않도록 높이 불변식을 복구하는 작업.
- **범위 탐색(Range Search)**: 키 정렬 순서를 활용하여 특정 구간의 원소들을 중위 순회로 연속 추출하는 기능.

</details>

![AVL과 레드블랙 트리의 키 수별 높이 상한](/study/diagrams/balanced-tree-height.svg)

> 키 수가 늘어도 두 선은 로그 증가하며 파란 AVL 높이 상한이 붉은 레드블랙보다 낮고, 각 균형 규칙의 이론적 상한임

- **키 순서 조건**으로 탐색 범위를 계층적으로 분할 축소
- **균형 유지**를 통한 탐색•삽입•삭제 연산의 $O(\log n)$ 시간 보장
- 키 정렬 순서를 보존한 **범위 탐색** 및 중위 순회(In-Order Traversal) 지원

#### 한줄 요약

- 노드 삽입/삭제 시 발생한 높이 불균형을 회전 및 색상 재지정 연산으로 정정하여 최악 높이를 $O(\log N)$으로 제어

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **루트(Root)**: 트리 탐색의 시작점이 되는 최상위 진입 노드.
- **회전(Rotation)**: 이진 탐색 트리의 정렬 순서를 보존하면서 부모-자식 간 포인터 링크를 재배치하여 서브트리 높이를 축소하는 연산.
- **색상 규칙(Color Invariants)**: 레드블랙 트리에서 루트-리프 간 블랙 노드 수 동일 유지 및 연속 레드 노드 금지를 규정하는 불변식.
- **노드 분할(Node Split)**: B-Tree에서 노드가 가득 찼을 때 중간 키를 부모 노드로 승격시키고 노드를 2개로 분리하는 연산.

</details>

```text
[ 균형 탐색 트리 아키텍처 및 재균형 구조 ]
┌──────────────────────────────┐
│ 루트 참조 (Root Reference)   │ ── 최상위 진입 노드 메모리 주소 보관
├──────────────────────────────┤
│ 탐색 제어기 (Search Engine)  │ ── 키 대소 비교 기반 하위 서브트리 경로 선택
├──────────────────────────────┤
│ 트리 노드 (Tree Node)        │ ── 키(Key), 데이터(Payload), 자식 포인터 보관
├──────────────────────────────┤
│ 균형 복구기 (Rebalancer)     │ ── 회전(LL/RR/LR/RL), 색상 변경, 노드 분할/병합
└──────────────────────────────┘
```

선의 의미: 루트 진입, 탐색 제어, 노드 데이터 저장 및 균형 복구 메커니즘 간의 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 루트 참조 | **루트**의 탐색 시작 위치 보관 |
| 탐색 제어기 | 키 대소로 **탐색 경로** 선택 |
| 트리 노드 | 키•자식 참조와 **균형 정보** 보관 |
| 균형 복구기 | **회전•색상 변경•분할**로 규칙 복구 |

#### 한줄 요약

- 탐색 제어기가 루트부터 키를 비교하고, 균형 복구기가 갱신된 노드의 규칙 위반을 바로잡음

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **균형 규칙 판정**: 노드 삽입/삭제 후 서브트리 높이 차, 레드-블랙 색상 조건, B-Tree 차수 조건 위반 여부를 검사하는 절차.
- **균형 복구(Rebalancing)**: 단일/이중 회전, 색상 반전, 노드 분할·병합을 통해 트리의 $O(\log n)$ 높이 상한을 회복하는 연산.

</details>

```text
키 처리 요청
   │
   ▼
1. 키 비교•자식 선택 (루트부터 하향 탐색)
   ├─ 목표 미도달: 자식 노드로 재귀 이동
   └─ 목표•삽입 위치 도달
      ├─ 조회: 데이터 반환
      └─ 갱신 (삽입 / 삭제)
         │
         ▼
2. 균형 규칙 판정 (높이 차 / 색상 규칙 / 노드 용량 검사)
├─ 충족: 처리 결과 반환
└─ 위반
   │
   ▼
3. 균형 복구 (회전 / 색상 변경 / 분할•병합)
   │
   ▼
처리 결과 반환
```

**동작 원리**

1. **키 비교 및 자식 선택**: 루트부터 키의 대소 관계를 비교하여 타깃 서브트리 경로 탐색
2. **균형 규칙 판정**: 삽입·삭제 경로 상에서 높이 차(AVL), 색상 조건(Red-Black), 노드 키 수(B-Tree) 위반 여부 검증
3. **균형 복구**: 규칙 위반 발생 시 트리 회전, 색상 변경, 노드 분할/병합을 수행하여 $O(\log n)$ 높이 불변식 복원

#### 한줄 요약

- 키 비교로 목표 경로를 찾고, 규칙 위반 시 회전·색상 변경·분할로 높이를 제한

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **B-Tree**: 노드당 다수의 키와 자식 포인터를 배치하여 트리 높이를 극소화하고 디스크 I/O를 절감하는 다진 균형 트리.
- **AVL 트리**: 좌우 서브트리의 높이 차(Balance Factor)를 항상 1 이하로 엄격히 유지하는 이진 탐색 트리.
- **레드블랙 트리(Red-Black Tree)**: 노드에 블랙/레드 색상을 부여하고 경로별 블랙 높이를 일치시켜 높이를 $2\log(n+1)$ 이하로 유지하는 트리.

</details>

| 비교 항목 | B-Tree 계열 | AVL 트리 | 레드블랙 트리 (Red-Black Tree) |
|:---|:---|:---|:---|
| 적용 기준 | **페이지 단위** 디스크/DB 인덱스 | 갱신이 드문 **조회 중심** 인메모리 | 삽입·삭제가 빈번한 **갱신 중심** 메모리 |
| 핵심 특징 | **다진 분기(Multi-way)** 및 높은 Fan-out | 좌우 **높이 차 1 이하** 엄격한 균형 | 노드 **색상 및 블랙 경로 규칙** 유지 |
| 한계 및 위험 | 분할·병합 시 추가적인 디스크 I/O 발생 | 삽입/삭제 시 엄격한 트리 **회전 오버헤드** | AVL 대비 다소 높은 트리 높이(탐색 경로) |

#### 한줄 요약

- 디스크 I/O 최적화는 B-Tree, 조회 중심 메모리는 AVL, 빈번한 갱신은 Red-Black 트리 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **B-Tree Fan-out**: 한 노드가 가질 수 있는 최대 자식 노드 수로, Fan-out이 클수록 전체 트리 높이가 낮아짐.
- **잠금 커플링(Lock Coupling, Crabbing)**: 트리 동시성 제어 시 부모 노드의 잠금을 획득한 후 자식 노드 잠금을 얻고 부모 잠금을 해제하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 낮은 **B-Tree 차수**로 트리 높이와 I/O 증가 | 페이지 크기(4KB/8KB)에 맞춘 B-Tree 차수 설정 | 트리 높이와 **I/O** 감소 |
| **워크로드**와 균형 정책 불일치로 비용 증가 | 조회 중심 AVL, 갱신 중심 레드블랙 선택 | 탐색•회전 비용의 균형 확보 |
| 분할•병합 중 장애로 일부 구조만 반영돼 경로 손상 | **복구 로그(WAL)•원자적 쓰기** 적용 | 장애 후 **구조 일관성** 복구 |
| 동시 노드 갱신의 **잠금 경합** | 루트•리프 방향 **잠금 커플링(Lock Crabbing)** 적용 | **교착** 방지와 동시 처리량 안정화 |

#### 한줄 요약

- **페이지 크기 정렬 Fan-out 최적화·워크로드별 트리 선정·WAL 기반 일관성 확보·Lock Crabbing 동시성 제어**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **B+Tree 확장**: B-Tree의 변형으로 모든 실제 데이터 레코드를 리프 노드에만 저장하고 리프 간 연결 리스트를 구성하여 순차 범위 검색을 극대화한 데이터베이스 표준 인덱스 구조.

</details>

- 외부 저장소 인덱스는 **B-Tree**, 메모리 조회 중심은 AVL 트리, 동적 갱신 중심은 **레드블랙 트리** 선택

#### 한줄 요약

- 외부 저장소는 B-Tree, 메모리 조회 중심은 AVL, 갱신 중심은 레드블랙을 선택
