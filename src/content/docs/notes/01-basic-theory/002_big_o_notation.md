## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **빅오 표기법(Big-O Notation, $O$)**: 입력이 충분히 커진 뒤 비용 증가율이 넘지 않는 점근 상한을 표기하는 수학적 점근 표기법.
- **실측값(Empirical Measurement)**: 운영 환경에서 직접 실측한 실행 시간 및 메모리 소모 수치.
- **비용 확장성(Cost Scalability)**: 입력 규모 증가에 따라 연산 횟수와 자원 소모량이 늘어나는 증가 추세.

</details>

- 정의/개념: 입력 데이터가 충분히 커질 때 비용 함수의 상한선이 특정 기준 함수의 상수배를 초과하지 않음을 수학적으로 증명하는 **빅오 표기법**
- 배경/필요성: 하드웨어별 **실측값**만으로는 입력 증가에 따른 **비용 확장성** 비교가 곤란하여 하드웨어 독립적인 수학적 상한 표준 필수

#### 한줄 요약

- 입력 규모 N이 대형화될 때 알고리즘 비용 함수 T(N)이 초과하지 않는 점근적 상한 정의

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지배항(Dominant Term)**: 입력 크기가 무한히 증가할 때 최고차 차수로서 비용 증가율을 결정하는 대표 항.
- **점근 추상화(Asymptotic Abstraction)**: 상수 계수와 하위 차수 항을 배제하고 최고차 항 기반의 비례 추세를 추출하는 기법.
- **상한 증인(Witness)**: 빅오 정의 성립 조건인 양의 상수 배율 $c$와 기준점 $n_0$의 순서쌍 $(c, n_0)$.

</details>

![비용 함수와 빅오 점근 상한](/study/diagrams/big-o-upper-bound.svg)

> 파란 $T(n)=n^2+2n$이 $n_0=2$부터 $2n^2$ 이하로 유효한 상한증인 기반 점근 상한 형성 양상

- 상수·하위항을 제외한 **지배항** 중심의 차수 분류를 통해 미미한 요소의 성능 분석 교란 방지
- 시스템 간 상수 배율 차이를 통합하는 **점근 추상화** 기법을 통해 알고리즘의 내재적 효율성 비교
- 양의 상수 및 기준점 조합 기반의 **상한 증인** 산정을 통해 수학적으로 엄밀한 성능 상한 경계 검증

#### 한줄 요약

- 초기 구간을 제외하고 비용 함수를 포괄하는 점근 상한 분류

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **비용 함수 $T(n)$(Cost Function $T(n)$)**: 입력 크기 $n$에 대해 알고리즘이 실행하는 기본 연산 횟수의 수학적 표현.
- **기준 함수 $g(n)$(Reference Function $g(n)$)**: 비용 함수의 점근적 증가율 비교 대상이 되는 표준 함수.
- **점근 상한(Asymptotic Upper Bound)**: 대규모 입력 구간에서 비용 증가율이 기준 함수의 상수배를 초과하지 않는 임계 경계.

</details>

```text
[ 빅오 점근 상한 증명 구조 ]
┌──────────────────────────────┐
│ 비용 함수 T(n) 산출          │
└──────────────┬───────────────┘
               │ [ 지배항 추출 및 기준 함수 g(n) 선정 ]
┌──────────────┴───────────────┐
│ 상한 증인 탐색 (c > 0, n0 > 0)│
└──────────────┬───────────────┘
               │ [ ∀n ≥ n0 : T(n) ≤ c · g(n) ]
┌──────────────┴───────────────┐
│ 점근 상한 O(g(n)) 확정       │
└──────────────────────────────┘
```

선의 의미: 비용 함수 $T(n)$에서 지배항 추출 후 기준 함수 $g(n)$ 및 상한 증인 $(c, n_0)$ 탐색을 거쳐 점근 상한을 확정하는 수학적 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 비용 함수 $T(n)$ | 기본 연산 횟수를 **비용 함수**로 표현 |
| 기준 함수 $g(n)$ | 증가율을 비교할 **기준 함수** 후보 표현 |
| 상한 증인 $c,n_0$ | **상한 증인**의 배율 및 기준점 지정 |
| 점근 상한 부등식 | 기준점 이후 모든 입력의 **점근 상한** 표현 |

#### 한줄 요약

- 비용 함수 $T(n)$과 기준 함수 $g(n)$ 간에 부등식 $T(n) \le c \cdot g(n)$을 만족하는 상수 $c>0$와 기준점 $n_0$의 존재성을 증명

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **양의 상수 $c$(Positive Constant $c$)**: 기준 함수를 확대하여 비용 함수의 최고 상한선으로 수용하는 조정 배율.
- **기준점 $n_0$(Threshold $n_0$)**: 점근 상한 부등식이 이후 모든 입력 조건에서 지속 성립하는 최소 입력 크기.

</details>

```text
[실행 비용 함수 T(n) 도출]
          │
          ▼
1. 지배항 추출 ──> 상수 및 저차항 제거 후 최고차 증가율 분리
          │
          ▼
2. 기준 함수 선정 ──> 지배항과 동일 차수의 표준 함수 g(n) 결정
          │
          ▼
3. 상한 증인 탐색 ──> 부등식을 만족하는 양의 상수 c > 0 및 기준점 n0 선정
          │
          ▼
4. 부등식 성립 증명 ──> ∀n ≥ n0 구간에서 T(n) ≤ c·g(n) 점근 상한 확정
```

$$
0 \le T(n) \le c \cdot g(n) \quad (n \ge n_0,\ c > 0)
$$

**동작 원리**

1. **비용 함수 산정**: 입력 크기 $n$에 따른 기본 연산 횟수를 집계하여 수학적 함수 $T(n)$을 수립
2. **상한 후보 선정**: 비용 함수에서 가장 빠르게 증가하는 최고차 **지배항**과 동등한 차수의 **기준 함수** $g(n)$을 선정
3. **상한 증인 탐색**: 기준 함수의 상수배가 비용 함수를 완전히 포괄할 수 있도록 **양의 상수 $c$**와 **기준점 $n_0$**의 쌍을 도출
4. **부등식 검증**: $n \ge n_0$인 모든 입력 구간에서 $T(n) \le c \cdot g(n)$이 지속 성립함을 수학적으로 증명하여 **점근 상한**을 확정

#### 한줄 요약

- 비용 함수의 지배항을 추출하여 기준 함수를 정의하고, 상한 증인 유효성을 검증하여 점근적 상한을 확정

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **빅세타(Big-Theta Notation, $\Theta$)**: 점근적 상한과 하한을 동시에 한정하여 정확한 차수를 보증하는 표기법.
- **빅오메가(Big-Omega Notation, $\Omega$)**: 알고리즘 비용 증가율의 점근적 하한 경계를 표기하는 표기법.
- **느슨한 상한(Loose Upper Bound)**: 실질 최고차 증가율보다 과도하게 높은 차수로 설정된 비효율적 상한 표기.

</details>

| 비교 항목 | 빅오 $O(g(n))$ | 빅세타 $\Theta(g(n))$ | 빅오메가 $\Omega(g(n))$ |
|:---|:---|:---|:---|
| 적용 기준 | 증가율의 **점근 상한**만 필요할 때 | 정확한 **점근 차수**가 필요할 때 | 증가율의 **점근 하한**만 필요할 때 |
| 핵심 특징 | 기준 함수 이하로 상한 제한 | 상한•하한을 같은 함수로 제한 | 기준 함수 이상으로 하한 제한 |
| 한계 및 위험 | **느슨한 상한**이면 정확한 차수 은폐 | 동일한 상•하한 증명 수식 필수 | **점근 상한** 판단 불가 |

#### 한줄 요약

- 상한 경계는 빅오(Big-O), 하한 경계는 빅오메가(Big-Omega), 상·하한 동시 바운딩은 빅세타(Big-Theta) 표기법 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **상수 비용(Constant Cost)**: 점근 차수 표기에서는 소거되나 실제 런타임 응답시간에 유의미한 영향력을 행사하는 고정 오버헤드.
- **입력 사례(Input Case)**: 동일 데이터 규모 내 조건 구성에 따른 최선·평균·최악 실행 상태 분류.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **느슨한 상한**으로 증가율과 후보 차이 은폐 | 성립하는 가장 낮은 **점근 차수**와 증인 제시 | 후보 간 점근 차수 구분 |
| 같은 차수에서 **상수 비용** 생략으로 응답시간 역전 | 목표 입력 구간의 동일 환경 **실측값** 병행 | 운영 구간의 실측값 반영 |
| **입력 사례**와 점근 상한 혼동으로 최악 사례를 빅오로 오인 | 최선•평균•최악 조건과 상•하한 표기 분리 | 사례 조건과 **점근 상한** 분리 |

#### 한줄 요약

- 느슨한 상한 대신 가장 낮은 차수를 증명하고, 동일 차수 간에는 실측 벤치마크로 후보를 가리며, 입력 사례와 점근 표기를 혼동하지 않는다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **성능 역전(Performance Crossover)**: 동일 점근 차수 알고리즘 간 상수 계수 차이로 인해 특정 입력 규모에서 실행 시간 우열이 뒤바뀌는 현상.

</details>

- 입력이 커지면 낮은 **점근 차수**, 같은 차수면 **실측값**으로 알고리즘 선택

#### 한줄 요약

- 점근 차수가 다르면 낮은 차수가 유리하고, 같은 차수면 운영 환경 실측으로 상수 비용까지 비교해야 최적 알고리즘을 고를 수 있다.
