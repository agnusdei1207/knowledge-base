## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **병렬 임의 접근 기계(Parallel Random Access Machine, PRAM)**: 동기 프로세서들이 하나의 공유 메모리를 사용한다고 가정하는 병렬 알고리즘 분석 모델
- **알고리즘 병렬성**: 하드웨어 세부와 분리해 동시에 수행할 수 있는 작업의 정도
- **공유 메모리 임의 접근**: 모든 프로세서가 같은 주소 공간의 원하는 위치를 단위 시간에 읽고 쓰는 가정

</details>

- 정의/개념: 다수의 동기 프로세서가 **공유 메모리**를 임의 접근한다고 가정하는 병렬 알고리즘 분석 모델
- 배경/필요성: 하드웨어별 구조 차이로 **알고리즘 병렬성** 비교 곤란

#### 한줄 요약

- PRAM은 여러 작업자가 같은 창고를 한 박자씩 쓴다고 가정해 알고리즘 자체의 병렬 단계 수를 비교한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **총 연산량 $W$**: 모든 프로세서가 수행하는 연산 수의 합
- **스팬 $S$**: 병렬화할 수 없는 최장 의존 경로의 길이
- **효율**: 투입한 전체 프로세서 시간 중 순차 작업에 실제 기여한 비율 $T_1/(pT_p)$
- **동기 단계**: 모든 프로세서가 같은 박자에 한 번의 연산과 메모리 접근을 수행하는 단계
- **병렬 비용 $pT_p$**: 프로세서 수와 병렬 실행시간을 곱한 전체 자원 사용량
- **순차 시간 $T_1$**: 같은 알고리즘을 프로세서 하나로 실행할 때의 시간

</details>

- **동기 단계**마다 공유 메모리에 단위 시간 접근
- **총 연산량•스팬**이 병렬 시간 하한 결정
- **비용•효율**로 프로세서 확장의 자원 기여도 평가

$$T_p \ge \max(W/p,\ S),\quad \text{효율}=\frac{T_1}{p\,T_p}$$

#### 한줄 요약

- 병렬 시간은 일을 프로세서에 나눈 시간과 건너뛸 수 없는 최장 의존 사슬보다 짧을 수 없다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **동기 클록**: 모든 프로세서의 단계 시작과 종료 시점을 맞추는 기준
- **공유 메모리**: 프로세서들이 공용 데이터와 부분 결과를 읽고 쓰는 저장 공간
- **충돌 정책**: 여러 프로세서가 같은 주소에 동시에 쓸 때 반영할 값을 정하는 규칙

</details>

```text
[PRAM]
   |
   +-- [프로세서 집합]
   +-- [공유 메모리]
   +-- [동기 클록]
   `-- [충돌 정책]
```

선의 의미: 병렬 실행•공유 저장•동기화•충돌 규칙의 정적 구성

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 집합 | 분할 작업의 **동기 연산•메모리 접근** 수행 |
| 공유 메모리 | 프로세서 간 **공용 데이터•부분 결과** 공유 |
| 동기 클록 | 모든 프로세서의 **단계 시작•종료** 정렬 |
| 충돌 정책 | 동시 쓰기 요청에서 **반영할 값** 선택 |

#### 한줄 요약
- 프로세서와 공유 메모리가 연산을 수행하고 동기 클록과 충돌 정책이 실행 순서를 통제한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **동시 쓰기 충돌**: 둘 이상의 프로세서가 같은 메모리 주소에 같은 단계에서 값을 쓰려는 상황
- **직렬화**: 충돌하는 병렬 작업을 한 번에 하나씩 처리하도록 순서를 강제하는 동작
- **충돌 정책**: 동시 쓰기 요청 가운데 최종 반영할 값을 정하는 규칙

</details>

```text
[전체 병렬 단계]
        |
        v
1. 동기 병렬 단계 시작
        |
        v
2. 병렬 연산•메모리 접근
        |
        v
3. 동시 쓰기 충돌 판정
        +-- 충돌
        |   `-- 4. 충돌 정책 적용
        |       `-- 단계 완료 판정으로
        `-- 미충돌
            `-- 단계 완료 판정으로

병렬 단계 완료 판정
        +-- 전체 미완료: 1부터 반복
        `-- 전체 완료: 병렬 알고리즘 결과
```

**동작 원리**

- **1. 동기 병렬 단계 시작**: 프로세서 실행 시점 정렬
- **2. 병렬 연산•메모리 접근**: 공용 데이터 읽기•부분 결과 쓰기
- **3. 동시 쓰기 충돌 판정**: 같은 주소의 쓰기 요청 검사
- **4. 충돌 정책 적용**: 공통•우선•결합 규칙으로 값 선택

#### 한줄 요약

- 여러 작업자가 같은 창고를 한 박자씩 쓰고 같은 칸에 쓰려 하면 정해진 규칙으로 하나를 선택한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **배타 읽기 배타 쓰기(Exclusive Read Exclusive Write, EREW)**: 읽기와 쓰기를 모두 배타로 제한하는 모델
- **동시 읽기 배타 쓰기(Concurrent Read Exclusive Write, CREW)**: 동시 읽기만 허용하는 모델
- **배타 읽기 동시 쓰기(Exclusive Read Concurrent Write, ERCW)**: 읽기는 배타, 쓰기는 동시 허용하는 모델
- **동시 읽기 동시 쓰기(Concurrent Read Concurrent Write, CRCW)**: 읽기와 쓰기를 모두 동시 허용하는 모델
- **메모리 접근 제약**: 같은 주소에 대한 동시 읽기•쓰기 허용 범위
- **배타•공유 접근**: 같은 메모리 주소를 한 프로세서만 사용하거나 여러 프로세서가 동시에 사용하는 방식
- **충돌 해결 정책**: CRCW 등에서 동시 쓰기 값 중 공통값•우선값•결합값을 선택하는 규칙

</details>

| PRAM 모델 | EREW | CREW | ERCW | CRCW |
|:---|:---|:---|:---|:---|
| 적용 기준 | 읽기•쓰기 **주소 충돌**이 없는 경우 | **공통 입력**만 동시에 읽는 경우 | 개별 입력을 **단일 주소**에 모으는 경우 | **동시 읽기•쓰기**가 모두 필요한 경우 |
| 핵심 특징 | 읽기•쓰기 모두 **배타** | 읽기 **공유**•쓰기 배타 | 읽기 배타•쓰기 **공유** | 읽기•쓰기 모두 **공유** |
| 한계 | 접근 제한에 따른 **단계 수** 증가 | 쓰기 경합의 별도 **직렬화** 비용 | 실용 사례 드문 **비대칭 제약** | **충돌 해결 정책**별 결과 차이 |

> 요약: 동시 접근 허용 시 **병렬 단계** 감소, **충돌 정책** 복잡도 증가

#### 한줄 요약

- 동시 읽기•쓰기를 더 허용할수록 단계 수는 줄지만 충돌을 처리할 구현 비용은 커진다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **리덕션 트리(Reduction Tree)**: 부분 결과를 트리 구조로 병합하는 방식
- **로컬 집계(Local Aggregation)**: 각 프로세서가 부분 결과를 먼저 요약하는 방식
- **워크 스틸링**: 유휴 프로세서가 다른 큐의 대기 작업을 가져와 부하를 분산하는 방식
- **장벽 병합**: 인접한 동기화 지점을 하나로 합쳐 대기 횟수를 줄이는 최적화
- **동적 스케줄링**: 실행 중 남은 작업량을 기준으로 작업을 프로세서에 다시 배정하는 방식
- **동기화 장벽(Barrier)**: 모든 프로세서가 지정 단계에 도달할 때까지 다음 실행을 기다리는 지점

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프로세서 증설에도 실행 시간 정체 | **스팬 분석•의존 작업 재분할** | **직렬 임계 경로** 단축 |
| 공유 주소 경합으로 대기 증가 | 데이터 분할•**리덕션 트리•로컬 집계** | **메모리 충돌** 완화 |
| 작업량 편차로 일부 프로세서 유휴 | **워크 스틸링•동적 스케줄링** | **부하 균형** 향상 |
| 동기화 단계가 지나치게 잦음 | 배치 확대•**인접 장벽 병합** | **동기화 비용** 감소 |

#### 한줄 요약

- 프로세서별 부분 합을 리덕션 트리로 병합해 공유 주소 쓰기 충돌을 줄인다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **메모리 경합**: 여러 프로세서가 같은 메모리 자원에 접근해 대기 시간이 늘어나는 현상
- **분할 재설계**: 의존 경로를 줄이도록 작업 단위를 다시 구성하는 작업
- **배치 재설계**: 경합을 줄이도록 데이터 위치를 다시 구성하는 작업

</details>

- **스팬•효율**과 메모리 경합을 측정해 분할•배치 재설계

#### 한줄 요약

- 프로세서를 늘려도 의존 시간•경합이 줄지 않으면 분할 단위와 데이터 배치를 바꾼다.
