## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **PRAM(Parallel Random Access Machine)**: 다수의 동기화된 프로세서가 단일 공유 메모리를 지연 없이 단위 시간 내에 임의 접근한다고 가정한 이론적 병렬 계산 모델.
- **공유 메모리(Shared Memory)**: 모든 병렬 프로세서가 단일 전역 주소 공간을 통해 데이터를 읽고 쓸 수 있는 가상 메모리.
- **동기식 프로세서(Synchronous Processors)**: 단일 전역 클록에 맞춰 매 단위 시간마다 읽기, 연산, 쓰기를 동시에 수행하는 프로세서 집합.

</details>

- 정의/개념: 동기 프로세서가 **공유 메모리**를 단위 시간에 접근하는 병렬 계산 모델
- 배경/필요성: 물리 하드웨어의 통신 지연 및 캐시 동기화 오버헤드로 인해 알고리즘 고유의 본질적 **병렬 처리 복잡도를 독립적으로 평가하기 어려운 한계**

#### 한줄 요약

- 통신 비용을 지운 자리에서 얻은 상한이므로, PRAM의 결과는 달성 가능한 최선이지 실제 성능의 예측치가 아니다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **작업량(Work, $W$)**: 순차 알고리즘으로 실행할 때 필요한 총 기본 연산 횟수($W = p \times T_p$).
- **깊이/시간(Depth/Span, $T_\infty$)**: 무한한 프로세서가 주어졌을 때 데이터 의존성에 의해 결정되는 최단 병렬 실행 시간.

</details>

- 물리적 통신 오버헤드를 추상화하여 **작업량($W$)과 병렬 실행 시간($T_p$)** 중심의 복잡도 분석
- 동시 읽기/쓰기 충돌 허용 수준에 따른 **4대 접근 모델 분류(EREW, CREW, ERCW, CRCW)**
- **브렌트 정리(Brent's Theorem)** 기반 유한한 프로세서 수($p$) 환경의 실행 시간 상한 도출

#### 한줄 요약

- 통신 지연을 추상화하여 작업량과 깊이를 분석하고 4대 접근 충돌 모델과 브렌트 정리를 제공

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **EREW(Exclusive Read Exclusive Write)**: 동일한 메모리 위치에 대한 동시 읽기와 동시 쓰기를 모두 금지하는 가장 엄격한 모델.
- **CRCW(Concurrent Read Concurrent Write)**: 동일한 메모리 위치에 대한 동시 읽기와 동시 쓰기를 모두 허용하는 가장 강력한 모델.

</details>

```text
[PRAM 병렬 컴퓨팅 구조]
  │
  ├─ [동기 프로세서군] (Processing Units)
  │     ├─ 전역 클록 동기화 (단일 스텝 락스텝 제어)
  │     └─ 병렬 프로세서 배열 (P_1 ~ P_p 연산 수행)
  │
  ├─ [통신 및 메모리 계층] (Interconnect & Memory)
  │     ├─ 무지연 상호연결망 (O(1) 임의 접근 추상 버스)
  │     └─ 전역 공유 메모리 (단일 공통 주소 공간 M)
  │
  └─ [메모리 접근 모델군] (Access Conflicts)
        ├─ 배타적 접근 (EREW, ERCW)
        ├─ 동시 읽기 허용 (CREW)
        └─ 동시 읽기/쓰기 허용 (CRCW: Common, Arbitrary, Priority)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 프로세서 배열 ($P_1 \dots P_p$) | 전역 클록에 맞춘 **읽기·계산·쓰기** 병렬 수행 |
| 무지연 상호연결망 | 프로세서와 메모리 간 **단위 시간 접근** 가정 |
| 전역 공유 메모리 ($M$) | 모든 프로세서가 접근하는 **전역 주소 공간** 제공 |
| 전역 동기 클록 | 프로세서 실행을 **단일 스텝**으로 동기화 |

#### 한줄 요약

- $p$개의 동기 프로세서, 무지연 연결망, 전역 공유 메모리로 구성되어 단위 시간 동기 연산을 수행

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **브렌트 정리(Brent's Theorem)**: 작업량 $W$와 깊이 $T_\infty$를 가진 PRAM 알고리즘을 $p$개 프로세서로 실행할 때 $T_p \le \frac{W}{p} + T_\infty$가 성립한다는 정리.

</details>

```text
병렬 작업 태스크(Work W) 및 프로세서 p개 할당
   |
   v
[ 1. 동기 사이클 개시 (전역 클록 동기화) ]
   |
   v
[ 2. 메모리 읽기 단계 (Read Phase) ] : 공유 메모리에서 데이터 인출
   |
   v
[ 3. 국소 연산 단계 (Compute Phase) ] : 프로세서별 독립 ALU 연산
   |
   v
[ 4. 메모리 쓰기 단계 (Write Phase) ]
   |
   +---> 쓰기 충돌 발생 시 (CRCW)  : [ 충돌 중재 규칙 적용 (Common/Priority) ]
   |
   +---> 단일/배타 쓰기 완료 (CREW) : 공유 메모리 값 갱신
   |
   v
[ 5. 동기 배리어 대기 및 차기 스텝 진행 ]
```

분기 결과: 동일 메모리 주소에 동시 쓰기 요청이 집중되면 CRCW 충돌 해결 규칙(Common/Arbitrary/Priority)에 따라 단일 승자를 결정하여 기록하고, 충돌이 없으면 즉시 메모리에 반영하여 동기 배리어로 분기한다.

**동작 원리**:
1. **동기 사이클 개시**: 단일 전역 클록에 맞추어 모든 병렬 프로세서($P_1 \dots P_p$)가 동일한 락스텝(Lock-step) 주기로 동기화된다.
2. **메모리 읽기 단계**: 각 프로세서가 전역 공유 메모리(M)로부터 필요한 피연산자 데이터를 단위 시간($O(1)$) 내에 동시에 인출한다.
3. **국소 연산 단계**: 인출된 데이터를 기반으로 각 프로세서 내부 ALU에서 독립적인 산술/논리 연산을 병렬 수행한다.
4. **메모리 쓰기 단계**: 연산 결과를 대상 전역 메모리 셀에 기록하며, 동시 쓰기 발생 시 모델 규약(Common, Priority 등)에 따라 충돌을 해소한다.
5. **동기 배리어 대기 및 완료**: 모든 프로세서가 쓰기 단계를 완료할 때까지 대기한 후 다음 클록 스텝으로 전이하며, 브렌트 정리에 따라 $T_p \le \frac{W}{p} + T_\infty$ 시간 내에 전체 태스크를 종료한다.

#### 한줄 요약

- 작업량을 프로세서에 나누되 의존 경로보다 빠를 수 없다는 상한을 계산

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **EREW(배타 읽기/쓰기)**: 동일 위치에 대한 동시 읽기와 쓰기를 모두 금지하는 가장 엄격한 모델.
- **CREW(동시 읽기/배타 쓰기)**: 여러 프로세서의 동시 읽기는 허용하되 동시 쓰기는 금지하는 표준 모델.
- **ERCW(배타 읽기/동시 쓰기)**: 동시 읽기는 금지하되 동시 쓰기를 허용하는 이론적 모델.
- **CRCW(동시 읽기/동시 쓰기)**: 동시 읽기와 쓰기를 모두 허용하며 충돌 중재 규칙이 필요한 최상위 모델.

</details>

| PRAM 접근 모델 | EREW | CREW | ERCW | CRCW |
|:---|:---|:---|:---|:---|
| 적용 기준 | 충돌 없는 **배타 접근** | 공유 데이터의 **동시 읽기** | 결과의 **동시 쓰기** | 이론적 병렬 상한 탐색 |
| 핵심 특징 | 읽기·쓰기 모두 배타 | 읽기 동시·쓰기 배타 | 읽기 배타·쓰기 동시 | 읽기·쓰기 모두 동시 |
| 한계 | 복제·병합 단계 증가 | 쓰기 직렬화 | 읽기 병렬성 제한 | **쓰기 충돌 규칙** 필요 |

#### 한줄 요약

- 읽기·쓰기 충돌 허용 범위에 따라 네 PRAM 접근 모델을 구분

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **BSP 모델(Bulk Synchronous Parallel)**: 계산 단계, 통신 단계, 동기화 배리어(Barrier)를 명시적으로 분리하여 실제 분산 메모리 환경을 모델링하는 실용적 병렬 모델.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| PRAM의 무제한 통신 가정이 실제 멀티코어 환경과 **불일치** | **BSP(벌크 동기 병렬) 및 분산 메모리 모델로 변환 설계** | 네트워크 통신 지연 및 캐시 일관성 오버헤드 반영 |
| CRCW 모델의 동시 쓰기 시 발생하는 **데이터 일관성 충돌** | **Common / Arbitrary / Priority 쓰기 충돌 규칙 명시** | 결정론적 실행 결과 보장 및 레이스 컨디션 차단 |
| 가용 물리 프로세서 수($p$) 제한 시 **스케줄링 오버헤드** | **브렌트 정리($T_p \le \frac{W}{p} + T_\infty$) 기반 최적 프로세서 수 산정** | 프로세서 투입 대비 최대 가속비(Speedup) 도출 |

#### 한줄 요약

- 통신 불일치는 BSP로 보정하고, 쓰기 충돌은 명시적 규칙으로 통제하며, 프로세서 수는 브렌트 정리로 최적화

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가속비(Speedup)**: 단일 프로세서 실행 시간 대비 $p$개 프로세서 병렬 실행 시간의 단축 비율($S_p = T_1 / T_p$).

</details>

- 멀티코어/GPU 병렬 알고리즘(병합 정렬, 전위 합 Prefix Sum)의 **이론적 병렬성 상한 규명 표준 모델**로 기능하며, 실무 하드웨어 구현에서는 **브렌트 정리($T_p \le W/p + T_\infty$) 기반 최적 스케줄링 및 실제 통신/동기화 비용을 반영한 BSP(Bulk Synchronous Parallel)/MPI 모델**로 전환하여 현실적 가속비를 달성

#### 한줄 요약

- 알고리즘 병렬성은 PRAM으로 분석하고 실제 성능은 BSP로 다시 검증
