## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **유한 오토마타(Finite Automaton)**: 유한한 상태와 전이 함수로 입력 문자열의 수용 여부를 판정하는 계산 모델이다.
- **결정적 유한 오토마타(Deterministic Finite Automaton, DFA)**: 각 입력에서 다음 상태가 하나로 정해지는 유한 오토마타이다.
- **비결정적 유한 오토마타(Nondeterministic Finite Automaton, NFA)**: 여러 다음 상태와 엡실론 전이를 허용하는 유한 오토마타이다.
- **형식 언어(Formal Language)**: 알파벳으로 만든 문자열 중 정해진 규칙을 만족하는 집합이다.
- **전이 함수(Transition Function)**: 현재 상태와 입력을 다음 상태에 대응시키는 함수이다.

</details>

- 정의/개념: 유한 상태와 입력 기호별 전이 규칙으로 문자열의 수용 여부를 판정하는 **유한 오토마타** 계산 모델이다.
- 배경/필요성: 자연어 표현이나 모호한 규격으로는 문자열 패턴과 어휘 규칙을 오류 없이 기계적으로 판정하기 어렵다.

#### 한줄 요약

- 입력 알파벳 $\Sigma$에 대한 상태 전이 함수 $\delta(q, a)$의 결정적/비결정적 매핑을 통해 정규 언어의 수용 여부를 판정한다.


## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **정규 언어(Regular Language)**: 유한 오토마타가 인식할 수 있는 문자열의 집합이다.
- **순차 처리**: 입력 기호를 앞에서부터 하나씩 소비하며 현재 상태를 갱신하는 방식이다.
- **인식 능력 동등성**: 서로 다른 오토마타가 같은 문자열 집합을 수용할 수 있는 성질이다.

</details>

![NFA 상태 수와 DFA 결정화 상태 수 상한을 비교한 차트](/study/diagrams/automata-subset-growth.svg)

> NFA 상태가 1개에서 5개로 늘 때 원래 상태 수는 1→5지만 부분집합 결정화의 이론적 상한은 2→32로 지수 증가한다.

- 유한 상태와 **전이 함수**만으로 문자열 수용을 판정한다.
- DFA•NFA의 **정규 언어**에 대한 **인식 능력 동등성**이 핵심이다.
- 입력 기호당 상태를 갱신하는 **순차 처리**가 핵심이다.

#### 한줄 요약

- Subset Construction (Powerset Construction) 알고리즘으로 NFA $\rightarrow$ DFA 변환이 가능하며, 두 오토마타의 정규 언어 인지 능력(Expressive Power)은 등가(Equivalence)이다.



## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **오토마타 5튜플 $(Q,\Sigma,\delta,q_0,F)$**: 상태 집합•입력 알파벳•전이 함수•시작 상태•수용 상태 집합으로 구성한 형식 구조이다.
- **입력 스트림(Input Stream)**: 문자열의 기호를 오토마타 실행기에 순서대로 제공하는 입력 경계이다.
- **수용 상태 집합 $F$**: 입력 소진 뒤 문자열 수용을 확정하는 상태의 집합이다.

- **오토마타 5-튜플(Automata 5-Tuple, $(Q, \Sigma, \delta, q_0, F)$)**: 상태 집합($Q$), 입력 알파벳($\Sigma$), 전이 함수($\delta$), 시작 상태($q_0$), 수용 상태 집합($F$)으로 구성된 정규 기계의 수학적 정의.
</details>

```text
유한 오토마타 M
├─ 상태 집합 Q
├─ 입력 알파벳 Σ
├─ 전이 함수 δ
├─ 시작 상태 q₀
└─ 수용 상태 집합 F
```

가지의 의미: 유한 오토마타를 이루는 5튜플의 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 상태 집합 Q | **상태 집합 Q**의 유한 상태 정의 |
| 입력 알파벳 Σ | **입력 알파벳 Σ**의 유한 기호 정의 |
| 전이 함수 δ | **전이 함수 δ**로 현재 상태•입력을 다음 상태에 대응 |
| 시작 상태 q0 | **시작 상태 q₀** 지정 |
| 수용 상태 집합 F | **수용 상태 집합 F**로 수용 여부 판정 |

> 요약: **5-튜플**($Q, \Sigma, \delta, q_0, F$)을 실행 주체의 상태•규칙으로 구성한다.

#### 한줄 요약

- $M=(Q,\Sigma,\delta,q_0,F)$로 상태•입력•전이•시작•수용 조건을 정의한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **현재 상태**: 지금까지 소비한 입력 이력을 유한하게 표현하는 오토마타의 기억 단위이다.
- **입력 소진**: 문자열의 모든 기호를 전이 함수에 전달해 더 처리할 기호가 없는 상태이다.
- **엡실론 폐쇄(Epsilon Closure)**: 엡실론 전이만 반복해 입력 없이 도달할 수 있는 모든 상태의 집합이다.

</details>

```text
입력 문자열
      │
      ▼
1. 초기 상태 구성
      │
      ▼
입력 기호 존재 여부
├─ 존재
│  └─ 2. 입력 기호 소비
│         │
│         ▼
│     3. 다음 상태 갱신
│         └─ 입력 기호 존재 여부로 반복
└─ 소진
      │
      ▼
4. 수용 상태 판정
      │
      ▼
수용 또는 거부
```

**동작 원리**

- **1. 초기 상태 구성**: DFA는 q₀, NFA는 {q₀}의 엡실론 폐쇄를 설정한다.
- **2. 입력 기호 소비**: 입력 스트림에서 기호 하나를 선택한다.
- **3. 다음 상태 갱신**: DFA 상태 또는 NFA 상태 집합을 갱신한다.
- **4. 수용 상태 판정**: 현재 상태와 수용 상태 집합을 비교한다.

#### 한줄 요약

- 입력 기호마다 상태를 갱신하고, 입력 소진 뒤 현재 상태와 수용 상태의 교집합으로 수용 여부를 판정한다.


## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **엡실론 전이($\varepsilon$-transition)**: 입력 기호를 소비하지 않고 NFA의 상태를 바꾸는 전이다.
- **상태 폭증(State Explosion)**: NFA 상태 조합이 DFA의 개별 상태가 되어 결정화 후 상태 수가 지수적으로 늘어나는 현상이다.
- **전이표(Transition Table)**: 현재 상태와 입력 기호에 대응하는 다음 상태를 표로 저장한 구조이다.
- **동적 정규식**: 실행 중 생성되거나 자주 변경되어 미리 고정된 전이표를 만들기 어려운 정규식이다.

- **결정적 유한 오토마타(Deterministic Finite Automaton, DFA)**: 각 상태에서 입력 기호마다 전이할 수 있는 다음 상태가 오직 하나로 결정되는 유한 상태 기계.
- **단일 상태 전이(Deterministic Single Transition)**: DFA에서 현재 상태와 입력 기호의 조합마다 오직 하나의 유일한 다음 상태로만 확정 전이하는 특성.
</details>

| 유한 오토마타 | DFA | NFA |
|:---|:---|:---|
| 적용 기준 | **전이표** 상주 가능한 고정 패턴 | 자주 바뀌는 **동적 정규식** 매칭 |
| 핵심 특징 | 입력마다 **단일 상태 전이** | **엡실론 전이**•다중 분기 허용 |
| 한계 | 패턴 복잡도에 따른 **상태 폭증** | 실행 시 **상태 집합** 추적 부담 |

#### 한줄 요약

- DFA는 기호마다 단일 상태를 갱신하고, NFA는 상태 집합과 엡실론 폐쇄를 추적한다.


## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **결정화(Determinization)**: NFA의 가능한 상태 집합을 하나의 DFA 상태로 대응시키는 변환이다.
- **정규식 서비스 거부(Regular Expression Denial of Service, ReDoS)**: 비효율적인 정규식과 악성 입력으로 자원을 고갈시키는 공격이다.
- **어휘 분석기(Lexical Analyzer)**: 문자 흐름을 식별자•숫자•연산자 같은 토큰으로 나누는 컴파일러 구성요소이다.
- **토큰 우선순위**: 여러 패턴이 동시에 수용될 때 반환할 토큰을 결정하는 순위 규칙이다.
- **시간 한도**: 정규식 매칭이 자원을 독점하지 않도록 허용하는 최대 실행 시간이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| NFA **결정화•상태 폭증** | 도달 가능한 **상태 집합**만 생성 | **전이표 메모리** 절감 |
| **엡실론 폐쇄** 누락 | 시작•매 전이 후 엡실론 폐쇄 계산 | NFA 수용 판정 오류 방지 |
| 여러 패턴의 **토큰 우선순위** 충돌 | 수용 상태에 토큰 우선순위 부여 | 결정적 토큰 선택 |
| 악성 정규식의 **ReDoS** 위험 | DFA•패턴 제한•**시간 한도** 적용 | **ReDoS** 방지 |
| 어휘 분석기**의 토큰 판별 | 정규식을 **DFA 전이표**로 변환 | 문자당 **단일 상태 전이 |

#### 한줄 요약

- 도달 상태만 지연 결정화하고 패턴•시간 한도를 적용해 상태 폭증과 ReDoS를 억제한다.


## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **상태 수 자원 한도**: 결정화한 DFA 상태와 전이표를 메모리에 유지할 수 있는 최대 규모이다.

</details>

- 고정 패턴과 상태 예산 이내면 **DFA**, 상태 폭증 우려 시 시간 한도를 둔 지연 결정화를 적용한다.

#### 한줄 요약

- 고정 패턴의 고속 처리는 DFA, 상태 폭증 우려는 시간 한도를 둔 지연 결정화를 선택한다.
