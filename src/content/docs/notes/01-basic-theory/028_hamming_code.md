## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **해밍 코드(Hamming Code)**: 패리티 검사 결과를 이진 위치값으로 조합해 한 비트 오류를 고치는 부호이다.
- **오류 정정 부호(Error-Correcting Code, ECC)**: 중복 비트를 추가해 저장•전송 과정의 오류를 검출하고 정정하는 부호이다.
- **신드롬(Syndrome)**: 패리티 재검사 결과를 조합해 얻는 오류 위치의 이진값이다.

</details>

- 정의/개념: 패리티 검사 결과를 신드롬으로 조합해 오류 위치를 찾아 한 비트를 고치는 **해밍 코드**이다.
- 배경/필요성: 메모리처럼 즉시 재전송할 수 없는 저장•전송 구간에서는 수신된 코드워드 자체로 비트 오류를 찾아 복구해야 한다.

#### 한줄 요약

- 패리티 비트를 $2^k$ 위치에 배치하고 패리티 검사 결과의 이진 조합인 신드롬 벡터 $S$를 통해 단일 비트 오류 위치를 실시간 복구한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **해밍 거리(Hamming Distance)**: 길이가 같은 두 비트열에서 값이 다른 자리의 개수이다.
- **단일 오류 정정 및 이중 오류 검출(Single Error Correction, Double Error Detection, SECDED)**: 한 비트 오류는 정정하고 두 비트 오류는 검출하는 방식이다.
- **패리티 오버헤드**: 원본 데이터 외에 오류 검사를 위해 추가되는 비트의 비율이다.
- **최소 해밍 거리**: 서로 다른 유효 코드워드 사이의 해밍 거리 가운데 가장 작은 값이다.
- **패리티 비트(Parity Bit)**: 지정된 비트 묶음의 1 개수를 짝수나 홀수로 맞추는 검사 비트이다.

</details>

![데이터 비트 수에 따른 최소 패리티 비율 차트](/study/diagrams/hamming-parity-overhead.svg)

> $2^p \ge d+p+1$을 만족하는 최소 $p$를 적용하면 데이터가 4→64비트로 늘 때 패리티 비율은 75%→10.94%로 감소한다.

- **신드롬**의 이진값이 오류 비트 위치를 직접 지시한다.
- **최소 해밍 거리** 3 확보로 **단일 오류 정정**이 핵심이다.
- 전체 **패리티 비트** 추가 시 **SECDED** 확장이 핵심이다.

> 데이터가 늘수록 **패리티 오버헤드** 비율 감소

#### 한줄 요약

- 신드롬 Vector가 Error Location Index를 직접 지시하며, Overall 패리티 비트를 추가한 SECDED(Single Error Correction Double Error Detection) 구조로 최소 해밍 거리 $d_{min}=4$를 확보한다.


## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **패리티 그룹**: 특정 패리티 비트가 검사하는 코드워드 위치의 집합이다.
- **코드워드(Codeword)**: 데이터 비트와 패리티 비트를 묶은 저장•전송 단위이다.
- **부호기(Encoder)**: 패리티를 붙여 코드워드를 만드는 구성요소이다.
- **복호기(Decoder)**: 신드롬으로 오류를 판정•정정하는 구성요소이다.
- **비트 반전 오류**: 저장•전송 중 한 비트 값이 0에서 1 또는 1에서 0으로 바뀐 오류이다.
- **원본 데이터**: 코드워드에서 패리티 비트를 제거한 정보 비트이다.
- **오류 위치**: 신드롬 이진값이 가리키는 손상 비트의 코드워드 자리이다.

</details>

```text
[해밍 부호기] -- [전송•저장 매체] -- [해밍 복호기]
                                             |
                                   [신드롬 판정기]
```

선의 의미: 부호기와 복호기가 전송•저장 매체의 코드워드에 접하고, 복호기가 신드롬 판정기를 이용하는 정적 연결 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 해밍 부호기 | 자리값별 **패리티 그룹** 계산•삽입 |
| 전송•저장 매체 | **비트 반전 오류**가 유입되는 구간 |
| 해밍 복호기 | 오류 정정 후 **원본 데이터** 추출 |
| 신드롬 판정기 | 패리티 결과로 **오류 위치** 판정 |

#### 한줄 요약

- 부호기가 패리티를 붙이고, 복호기와 신드롬 판정기가 매체에서 바뀐 비트의 위치를 찾아 원본을 복구한다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **패리티 위치**: 코드워드의 1•2•4•8처럼 2의 거듭제곱 자리에 배치하는 검사 비트 위치이다.
- **$2^p \geq d+p+1$**: 데이터 $d$비트의 모든 오류 위치와 정상 상태를 구분하는 최소 패리티 $p$ 조건이다.
- **오류 비트 반전**: 신드롬으로 위치가 특정된 부호 비트의 값을 반전하여 원래 전송 비트로 복원하는 정정 동작이다.

</details>

```text
[원본 데이터 d비트]
          |
          v
1. 패리티 수•위치 결정
          |
          v
2. 코드워드 생성
          |
          v
[전송•저장 매체]
          |
          v
3. 신드롬 계산
          |
          +-- 0 ------> [정상 코드워드] --------+
          |                                    |
          `-- 0 아님 -> 4. 오류 비트 반전 -----+
                                               |
                                               v
                                      [원본 데이터 추출]
```

> 비트 배치: 패리티는 1•2•4•8… 위치에 삽입
>
> 패리티 수 조건: $2^p \geq d+p+1$
>
### 동작 원리

- **1. 패리티 수•위치 결정**: 조건식으로 개수와 자리를 산정한다.
- **2. 코드워드 생성**: 패리티 그룹을 계산해 비트 삽입이다.
- **3. 신드롬 계산**: 패리티 재검사로 오류 위치를 판정한다.
- **4. 오류 비트 반전**: 신드롬 위치의 단일 비트 정정이다.

#### 한줄 요약

- $2^p \ge d+p+1$ 수식에 따라 패리티 비트를 계산 및 수신 측에서 신드롬 $S = S_p S_{p-1} \dots S_1$ 산출 후 $S \neq 0$인 경우 비트 반전 정정을 수행한다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **단일 오류 정정(Single Error Correction, SEC)**: 코드워드의 단일 비트 오류 위치를 식별해 정정하는 능력이다.
- **순환 중복 검사(Cyclic Redundancy Check, CRC)**: 생성 다항식의 나머지로 버스트 오류를 검출하는 방식이다.
- **버스트 오류(Burst Error)**: 연속된 비트 구간에서 여러 비트가 함께 손상된 오류이다.
- **ECC 메모리**: 오류 검출•정정 부호를 사용해 저장 비트 손상을 자동 처리하는 메모리이다.
- **패킷 전송**: 오류 검출 뒤 원본 데이터의 재전송을 요청할 수 있는 통신 구간이다.
- **전체 패리티 비트**: 코드워드 전체의 1 개수 패리티를 검사해 SEC 결과에서 이중 오류를 구분하는 비트이다.
- **이중 오류 오정정**: 두 비트가 손상됐지만 단일 오류로 잘못 해석해 정상 비트까지 뒤집는 현상이다.
- **다중 오류**: 한 코드워드에서 둘 이상의 비트가 손상된 상태이다.

</details>

| 오류 검출•정정 부호 | 해밍 코드(SEC) | SECDED | CRC |
|:---|:---|:---|:---|
| 적용 기준 | 1비트 오류 위주이고 **오버헤드**를 줄일 때 | 2비트 검출까지 요구하는 **ECC 메모리** | 검출만으로 충분한 **패킷 전송** 구간 |
| 핵심 특징 | **신드롬** 기반 1비트 정정 | **전체 패리티 비트** 추가로 2비트 검출 | **다항식 나머지** 기반 검출 |
| 한계 | **이중 오류 오정정**으로 손상 확대 | 3비트 이상 **다중 오류** 보장 없음 | 자체 **정정 불가**로 재전송 필요 |

#### 한줄 요약

- SEC(Single Error Correction), SECDED(ECC Memory), CRC(Cyclic Redundancy Check - Polynomial Division based Detection)로 가용성 및 신뢰성 환경에 맞춤 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **잠복 오류(Latent Error)**: 즉시 드러나지 않은 채 저장장치에 남아 다른 오류와 겹칠 수 있는 손상이다.
- **메모리 스크러빙**: 메모리를 주기적으로 읽고 오류를 정정해 손상 누적을 막는 작업이다.
- **인터리빙(Interleaving)**: 연속 비트를 여러 코드워드에 분산해 버스트 오류를 단일 오류들로 흩는 기법이다.
- **패리티 부족**: 데이터 비트 수에 비해 검사 비트가 적어 정상과 모든 오류 위치를 구분하지 못하는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| SEC의 **이중 오류 오정정** | 전체 패리티를 추가한 **SECDED** | 이중 오류 오정정 방지 |
| **잠복 오류** 누적 | 주기적 **메모리 스크러빙** | **다중 오류** 발전 방지 |
| 데이터 증가의 **패리티 부족** | $2^p \geq d+p+1$ 조건 재계산 | 모든 오류 위치를 **신드롬**으로 구분 |
| **버스트 오류**에 단독 적용 | **인터리빙**으로 연속 오류 분산 | **단일 오류 정정** 범위 회복 |

#### 한줄 요약

- DRAM Controller의 Memory Scrubbing 및 Data 인터리빙을 결합하여 잠복 오류 Accumulation 및 버스트 오류를 방지한다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **재전송 가능성**: 오류 검출 후 원본 데이터를 다시 요청해 받을 수 있는 운영 조건이다.
- **오류 형태**: 단일•이중•버스트처럼 한 코드워드에서 예상되는 비트 손상의 분포이다.

</details>

- **오류 형태•재전송 가능성**에 따라 **SEC•SECDED•CRC**를 선택한다.

#### 한줄 요약

- In-place Single Bit Correction은 SEC/SECDED, ARQ 기반 Network Retransmission 구간은 CRC Error Detection을 적용 체계 적용
