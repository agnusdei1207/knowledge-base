## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **분할 정복(Divide and Conquer)**: 문제를 독립된 부분으로 나눠 재귀로 해결한 뒤 부분 해를 결합하는 설계 기법
- **독립 부분 문제**: 다른 부분 문제의 중간 결과 없이 따로 해결할 수 있는 작은 문제

</details>

- 정의/개념: 문제를 **독립 부분 문제로 분할**해 재귀로 해결한 뒤 부분 해를 결합하는 **알고리즘 설계 기법**

#### 한줄 요약

- 큰 보고서를 독립된 묶음으로 나눠 여러 사람이 처리한 뒤 한 권으로 합치듯, 큰 문제를 나누고 부분 해를 결합한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상호 비의존성**: 한 부분 문제를 푸는 동안 다른 부분 문제의 계산이나 답을 요구하지 않는 성질
- **결합 비용(Combine Cost)**: 부분 문제의 해를 전체 해로 합치는 데 추가로 드는 시간과 메모리
- **호출 깊이(Call Depth)**: 종료 조건에 도달하기 전 재귀 함수가 연속으로 자신을 호출한 횟수

</details>

![균형 분할과 불균형 분할의 최대 재귀 깊이](/study/diagrams/divide-conquer-depth.svg)

> 입력이 커질수록 붉은 불균형 분할의 호출 깊이는 선형 증가하지만 파란 절반 분할은 로그 증가하며, 최대 재귀 깊이의 이론값이다.

- 같은 형태 부분 문제에 동일 **재귀 해법** 반복 적용
- 부분 문제 **상호 비의존성**에 따른 **병렬 처리**
- 분할 균형과 **결합 비용**에 따라 달라지는 총 수행 시간

#### 한줄 요약

- 여러 사람이 독립된 문서 묶음을 동시에 끝내도 묶음을 나누고 합치는 시간이 길면 전체 마감은 빨라지지 않는다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **종료 조건(Base Case)**: 재귀를 멈추고 답을 직접 구하는 최소 입력 조건
- **호출 스택(Call Stack)**: 재귀 호출의 복귀 위치와 부분 해를 쌓아 두는 메모리 영역
- **결합기**: 반환된 부분 해를 모아 상위 문제의 해를 만드는 구성요소

</details>

```text
분할 정복 구조
├─ 재귀 제어기
├─ 부분 문제 실행기
├─ 호출 스택
└─ 결합기
```

가지의 의미: 재귀•분할 실행•복귀•결합의 정적 책임 분리

| 구성요소 | 책임 |
|:---|:---|
| 재귀 제어기 | **종료 조건** 판정•재귀 흐름 통제 |
| 부분 문제 실행기 | 상호 비의존 **부분 문제** 분할•해결 |
| 호출 스택 | **복귀 위치•부분 해** 보관 |
| 결합기 | 부분 해로 **전체 해** 구성 |

#### 한줄 요약

- 재귀 제어기가 문제를 나누고 복귀 정보를 스택에 보관한 뒤, 결합기가 반환된 부분 해를 합친다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **복귀 문맥**: 재귀 호출을 마친 뒤 돌아갈 위치와 부분 해를 결합하는 데 필요한 정보
- **분할(Divide)**: 문제를 독립된 작은 부분 문제로 나누는 단계
- **정복(Conquer)**: 부분 문제를 재귀로 해결하는 단계
- **결합(Combine)**: 부분 문제의 결과를 전체 해로 합치는 단계
- **상위 해**: 같은 재귀 단계의 부분 해들을 결합해 얻은 더 큰 문제의 결과

</details>

```text
전체 문제
   │
   ▼
1. 종료 조건 판정
├─ 최소 문제
│  └─ 2. 기저 해 계산
│         │
│         └─ 전체 해 반환
└─ 분할 가능
   │
   ▼
3. 부분 문제 분할
   │
   ▼
4. 부분 문제 재귀 해결
   │
   ▼
5. 부분 해 결합
   │
   └─ 전체 해 반환
```

**동작 원리**

1. **종료 조건 판정**: 직접 풀 수 있는 최소 입력 여부 확인
2. **기저 해 계산**: 최소 문제의 답을 직접 산출
3. **부분 문제 분할**: 입력을 상호 독립된 작은 문제로 분리
4. **부분 문제 재귀 해결**: 같은 해법으로 각 부분 문제 처리
5. **부분 해 결합**: 부분 결과로 상위 문제의 해 구성

#### 한줄 요약

- 큰 상자를 작은 상자로 계속 나누고 스택에 붙인 귀환표를 따라 돌아오며, 각 상자의 답을 합쳐 전체 답을 만든다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **동적 계획법(Dynamic Programming, DP)**: 중복되는 부분 문제의 해를 저장•재사용하는 기법
- **점화식(Recurrence Relation)**: 하위 상태값을 결합해 현재 상태값을 계산하는 관계식
- **상태 공간(State Space)**: 동적 계획법에서 서로 구분해 저장해야 하는 모든 상태의 집합
- **중복 부분 문제(Overlapping Subproblems)**: 같은 작은 문제가 여러 계산 경로에서 반복해 나타나는 성질
- **불균형 분할**: 부분 문제 크기가 한쪽으로 치우쳐 재귀 깊이와 수행시간이 커지는 분할

</details>

| 문제 분해 기법 | 분할 정복 | 동적 계획법 |
|:---|:---|:---|
| 적용 기준 | **중복 부분 문제** 부재•독립 분할 가능 | 동일 상태 반복•**점화식** 정의 가능 |
| 핵심 특징 | 부분 해를 **재귀 결합** | **상태값 표** 저장•재사용 |
| 한계 | **불균형 분할**•과다 **결합 비용** | **상태 공간** 증가에 따른 메모리 초과 |

> 요약: 부분 문제의 중복 여부로 **분할 정복•DP** 선택

#### 한줄 요약

- 서로 다른 퍼즐 조각이면 따로 풀어 합치고, 같은 조각이 반복되면 답을 표에 적어 재사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **임계 크기(Threshold Size)**: 재귀 호출보다 반복 처리가 유리해지는 부분 문제의 크기
- **제자리 결합(In-place Merge)**: 큰 별도 배열 없이 기존 저장 공간에서 부분 해를 합치는 방식
- **동적 스케줄링(Dynamic Scheduling)**: 실행 중 남은 작업량에 따라 부분 문제를 처리 장치에 다시 배정하는 방식
- **깊이 제한**: 재귀가 허용된 단계에 도달하면 다른 알고리즘으로 전환하는 기준
- **호출 오버헤드(Call Overhead)**: 함수 호출과 복귀 문맥 관리에 드는 추가 시간과 메모리
- **꼬리 지연(Tail Latency)**: 가장 늦게 끝나는 일부 작업 때문에 전체 완료가 지연되는 시간

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **불균형 분할**로 호출 깊이•최악 시간이 선형 퇴화 | 균형 분할과 깊이 제한 적용 | 재귀 깊이와 **최악 수행시간 상한** 통제 |
| 작은 부분 문제에서 재귀 호출 비용이 계산량 초과 | **임계 크기**부터 반복 알고리즘 전환 | 작은 입력의 **호출 오버헤드 감소** |
| 높은 **결합 비용**으로 공간•복사량이 분할 이득 상쇄 | 버퍼 재사용 또는 **제자리 결합** 적용 | 결합 단계의 **메모리•복사 비용 감소** |
| 병렬 작업 크기 편차로 처리 장치 유휴•꼬리 지연 | 작업 세분화와 **동적 스케줄링** | 처리 장치 간 **부하 균형 향상** |

#### 한줄 요약

- 짐을 비슷한 크기로 나눠 한 작업자에게 일이 몰리는 것을 방지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **병렬 이득**: 독립 부분 문제를 동시에 실행해 줄인 전체 처리 시간
- **분할 비용**: 문제를 작은 부분 문제로 나누는 데 필요한 자원

</details>

- 분할•결합 비용이 병렬 이득보다 작을 때 **분할 정복** 적용

#### 한줄 요약

- 짐을 나누고 다시 모으는 시간이 여러 사람이 동시에 처리해 아낀 시간보다 짧을 때만 분할 정복을 선택한다.
