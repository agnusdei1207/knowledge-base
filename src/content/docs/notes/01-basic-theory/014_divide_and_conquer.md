## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **재귀 정복(Conquer)**: 하위 기저 조건까지 재귀 호출로 문제를 해결하는 처리 단계.
- **결합 연산(Combine)**: 독립적으로 해결된 개별 부분 해들을 하나로 병합하여 전체 해를 도출하는 단계.
- **순차 실행(Sequential Execution)**: 부분 문제를 한 처리 흐름에서 차례로 해결해 병렬 실행 이득을 얻지 못하는 방식.

</details>

- 정의/개념: 독립 부분 문제를 **재귀 정복**한 뒤 **결합**하는 설계 패러다임
- 배경/필요성: 단일 대규모 문제를 순차적으로 전수 처리할 때의 비효율($O(n^2)$ 이상)을 극복하고, 문제를 상호 독립적인 작은 부분 문제로 분할(Divide)하여 정복(Conquer) 및 결합(Combine)함으로써 **재귀적 다항/로그 시간($O(n \log n)$) 단축과 병렬 처리 확장성을 실현**할 필요

#### 한줄 요약

- 분할로 줄인 계산량보다 결합에 드는 비용이 크면 오히려 손해이므로, 분할 정복의 이득은 두 비용의 차액으로 결정된다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상호 비의존성(Mutual Independency)**: 한 부분 문제를 해결하는 과정이 다른 부분 문제의 계산 결과나 중간 상태에 일체 종속되지 않는 성질.
- **결합 비용(Combine Cost)**: 하위 부분 문제들의 해를 상위 해로 병합하는 데 소요되는 시간 및 공간 복잡도(예: 병합 정렬의 $O(n)$ 병합).
- **마스터 정리(Master Theorem)**: $T(n) = aT(n/b) + f(n)$ 형태의 분할 정복 재귀식 점근 복잡도를 정량적으로 판별하는 수학적 정리.

</details>

![균형 분할과 불균형 분할의 최대 재귀 깊이](/study/diagrams/divide-conquer-depth.svg)

> 입력이 커질수록 붉은 불균형 분할의 호출 깊이는 선형 증가하지만 파란 절반 분할은 로그 증가하며, 최대 재귀 깊이의 이론값임

- 하위 문제에 동일 규칙을 반복 적용하는 **재귀적 문제 해결** 구조
- 부분 문제 간 **상호 비의존성** 활용한 독립 병렬 처리 지원
- 균등 분할 여부와 **결합 비용** 크기에 따른 전체 시간복잡도($O(n \log n)$) 결정

#### 한줄 요약

- 부분 문제 간의 상호 비의존성을 활용하여 병렬 처리를 달성하되, 결합 단계의 시간·공간 오버헤드를 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **기저 조건(Base Case)**: 더 이상 분할할 필요 없이 $O(1)$ 시간에 즉시 정답을 반환하는 최소 단위 입력 크기.
- **호출 스택(Call Stack)**: 재귀 호출 시 복귀 주소(Return Address)와 지역 변수 상태를 보관하는 시스템 메모리 영역.

</details>

```text
[분할 정복 처리기]
|
+-- [분할 제어기]
+-- [재귀 정복기]
|   `-- [호출 스택]
`-- [결과 결합기]
    `-- [결합 버퍼]
```

선의 의미: 가지는 처리기의 소유 관계

| 구성요소 | 책임 |
|:---|:---|
| 분할 제어기 | 원래 문제를 상호 독립적인 **부분 문제**들로 분할 |
| 재귀 정복기 | **기저 조건** 판정 및 하위 문제의 재귀적 독립 해결 |
| 결과 결합기 | 개별 **부분 해**들을 전체 상위 해로 병합 |
| 호출 스택·결합 버퍼 | 재귀 **복귀 문맥**과 결합용 보조 공간 보관 |

#### 한줄 요약

- 재귀 제어기(Base Case 판정), 호출 스택(복귀 문맥), 결합 함수가 연계되어 하위 정복 결과를 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 크기(Threshold Size)**: 재귀 호출 오버헤드가 실제 연산량보다 커져 반복문(Loop) 기반 알고리즘으로 전환하는 최적의 서브문제 크기.

</details>

```text
전체 문제 P(N)
   │
   ▼
1. 종료 조건 판정 (N ≤ Base Case Threshold)
├─ 참 (기저 도달): 기저 해 직접 계산 후 즉시 반환 ($O(1)$)
└─ 거짓 (분할 가능)
   │
   ▼
2. 부분 문제 분할 (N ──► N/2, N/2)
   │
   ▼
3. 부분 문제 재귀 정복 (T(N/2) 각각 독립 실행)
   │
   ▼
4. 부분 해 결합 (Combine Partial Solutions)
   │
   ▼
최종 해 반환
```

**동작 원리**
1. **종료 조건 판정**: 기저 조건 도달 여부를 확인해 최소 크기 도달 시 기저 해 즉시 반환
2. **부분 문제 분할**: 최소 크기가 아니면 입력을 독립적인 작은 부분 문제들로 분할
3. **부분 문제 재귀 정복**: 각 부분 문제에 대해 재귀 호출을 수행해 독립적으로 부분 해 도출
4. **부분 해 결합**: 반환된 하위 부분 해들을 결합 규칙에 따라 병합해 상위 해 구축

#### 한줄 요약

- 종료 조건까지 분할하고, 재귀에서 복귀하며 부분 해를 상위 해로 결합

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **독립 부분 문제(Independent Subproblems)**: 분할 정복에서 각 하위 문제의 계산이 다른 하위 문제에 영향을 주지 않고 중복 없이 독립적으로 풀리는 특성.
- **중복 부분 문제(Overlapping Subproblems)**: 동적 계획법에서 동일한 하위 문제가 재귀 트리 상에서 반복적으로 나타나 캐싱이 필요한 특성.

</details>

| 설계 패러다임 | 분할 정복 (Divide & Conquer) | 동적 계획법 (Dynamic Programming) |
|:---|:---|:---|
| 적용 기준 | **독립 부분 문제** 분할 및 결합 가능 시 | 동일한 **중복 부분 문제** 빈번히 재출현 시 |
| 핵심 특징 | **분할·정복·결합** 하향식 재귀 구조 | 하위 상태값을 **DP 캐시 테이블**에 저장 및 재사용 |
| 한계 | 피벗 불균형 시 최악 $O(n^2)$ 선형 퇴화 | 상태 차원 증가 시 **공간복잡도** 급증 |

#### 한줄 요약

- 중복 부분 문제가 없으면 분할 정복(D&C), 동일 서브문제가 무수히 재출현하면 DP(Memoization)를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **제자리 결합(In-Place Merge)**: 추가적인 대규모 보조 배열 할당 없이 기존 버퍼 내에서 포인터 스왑으로 데이터를 병합하는 기법.
- **임계값 기반 하이브리드 전환**: 재귀 호출 깊이가 깊어지거나 크기가 작아질 때(예: $N \le 16$) 삽입 정렬 등으로 전환하는 기법(Timsort).
- **작업 훔치기(Work-Stealing)**: Fork-Join 프레임워크에서 유휴 스레드가 다른 바쁜 스레드의 덱(Deque) 꼬리에서 작업을 가져와 처리하는 동적 부하 분산 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **불균형 분할**로 인한 호출 깊이와 최악 수행시간이 선형 퇴화 | 균형 분할(중간값 피벗)과 **재귀 깊이 제한** 적용 | 재귀 깊이 및 최악 수행시간 통제 |
| 작은 부분 문제에서 재귀 호출 비용이 계산량 초과 | **임계 크기($N \le 16$)** 도달 시 반복 알고리즘 전환 | 작은 입력의 **호출 오버헤드** 대폭 감소 |
| 높은 **결합 비용**으로 공간·복사량이 분할 이득 상쇄 | 버퍼 재사용 또는 **제자리 결합** 적용 | 결합 단계의 추가 메모리 및 복사 오버헤드 감소 |
| 병렬 서브태스크 크기 편차에 따른 프로세서 유휴 및 꼬리 지연 발생 | Fork-Join 프레임워크 및 **동적 작업 훔치기** | 코어 간 **부하 균형** 극대화 |

#### 한줄 요약

- 작은 부분 문제는 임계값에서 반복 알고리즘으로 전환하고, 결합 비용이 크면 제자리 병합을 적용하며, 병렬 환경에서는 Work-Stealing으로 코어 간 부하를 균등히 나눈다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **분할 정복 적용 타당성**: 분할 및 결합에 소요되는 총비용이 전체 병렬화 및 점근적 시간 단축 이득보다 작을 때 성립하는 설계 판단.

</details>

- 정렬(병합/퀵 정렬), 고속 푸리에 변환(FFT) 및 분산 MapReduce의 **핵심 알고리즘 설계 모델**로 확립되었으며, 실무에서는 **마스터 정리를 통한 결합 오버헤드 통제 및 작은 부분 문제의 반복문 하이브리드 전환(Timsort/Introsort), Fork-Join 작업 훔치기(Work-Stealing)**와 결합하여 고성능을 달성

#### 한줄 요약

- 분할•결합 비용이 병렬 이득보다 작을 때 적용하고, 작은 문제는 반복 방식으로 전환
