## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **분할 정복(Divide and Conquer)**: 원형 문제를 상호 독립적인 작은 부분 문제로 분할하고, 각각을 재귀적으로 해결(정복)한 후 결합하여 전체 해를 도출하는 알고리즘 설계 패러다임.
- **독립 부분 문제(Independent Subproblems)**: 하위 문제 간에 데이터 공유나 상태 중복 없이 완전히 독립적으로 계산 가능한 부분 문제.
- **결합기(Combiner)**: 하위 부분 문제들의 개별 부분 해(Partial Solution)를 취합하여 상위 문제의 최종 해로 합성하는 모듈.

</details>

- 정의/개념: 큰 문제를 독립된 부분 문제로 나누어 재귀적으로 해결한 뒤 부분 해를 결합하는 **분할 정복(Divide & Conquer) 알고리즘 설계 기법**
- 배경/필요성: 대규모 원형 문제를 단일 연산으로 직접 해결하면 $O(n^2)$ 이상의 고비용이 발생하므로 **균형 분할 기반 $O(n \log n)$ 고속화 및 병렬화 필수**

#### 한줄 요약

- 원형 문제를 상호 독립적인 부분 문제로 분할하고, 재귀적으로 정복한 후 결합 연산으로 최종 해를 구축

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **상호 비의존성(Mutual Independency)**: 한 부분 문제를 해결하는 과정이 다른 부분 문제의 계산 결과나 중간 상태에 일체 종속되지 않는 성질.
- **결합 비용(Combine Cost)**: 하위 부분 문제들의 해를 상위 해로 병합하는 데 소요되는 시간 및 공간 복잡도(예: 병합 정렬의 $O(n)$ 병합).
- **마스터 정리(Master Theorem)**: $T(n) = aT(n/b) + f(n)$ 형태의 분할 정복 재귀식 점근 복잡도를 정량적으로 판별하는 수학적 정리.

</details>

![균형 분할과 불균형 분할의 최대 재귀 깊이](/study/diagrams/divide-conquer-depth.svg)

> 입력이 커질수록 붉은 불균형 분할의 호출 깊이는 선형 증가하지만 파란 절반 분할은 로그 증가하며, 최대 재귀 깊이의 이론값임

- 동일한 알고리즘을 하위 부분 문제에 반복 적용하는 **재귀적 문제 해결(Divide $\to$ Conquer $\to$ Combine)**
- 부분 문제 간의 **상호 비의존성**을 활용한 완벽한 **멀티코어/분산 병렬 처리(Parallel Processing)**
- 분할의 균형성(균등 분할)과 **결합 비용**의 크기에 따라 전체 시간복잡도($O(n \log n)$) 결정

#### 한줄 요약

- 부분 문제 간의 상호 비의존성을 활용하여 병렬 처리를 달성하되, 결합 단계의 시간·공간 오버헤드를 통제

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **기저 조건(Base Case)**: 더 이상 분할할 필요 없이 $O(1)$ 시간에 즉시 정답을 반환하는 최소 단위 입력 크기.
- **호출 스택(Call Stack)**: 재귀 호출 시 복귀 주소(Return Address)와 지역 변수 상태를 보관하는 시스템 메모리 영역.

</details>

```text
[ 분할 정복 3단계 아키텍처 ]
┌──────────────────────────────┐
│ 1. 분할 제어기 (Divide)      │ ── 문제를 독립적인 k개의 부분 문제로 분할
├──────────────────────────────┤
│ 2. 재귀 정복기 (Conquer)     │ ── 기저 조건(Base Case)까지 재귀적 독립 해결
├──────────────────────────────┤
│ 3. 결과 결합기 (Combine)     │ ── 하위 부분 해들을 상위 최종 해로 병합
├──────────────────────────────┤
│ 호출 스택 / 힙 버퍼 (Memory) │ ── 재귀 호출 문맥 및 결합용 보조 공간 관리
└──────────────────────────────┘
```

선의 의미: 분할, 정복, 결합 모듈 및 재귀 메모리 관리 간의 분할 정복 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 재귀 제어기 | **종료 조건** 판정 및 재귀 호출 흐름 통제 |
| 부분 문제 실행기 | 상호 비의존 **부분 문제** 분할 및 정복 |
| 호출 스택 | **복귀 위치** 및 **부분 해** 보관 |
| 결합기 | **부분 해**들을 전체 최종 해로 결합 |

#### 한줄 요약

- 재귀 제어기(Base Case 판정), 호출 스택(복귀 문맥), 결합 함수가 연계되어 하위 정복 결과를 통합

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **임계 크기(Threshold Size)**: 재귀 호출 오버헤드가 실제 연산량보다 커져 반복문(Loop) 기반 알고리즘으로 전환하는 최적의 서브문제 크기.

</details>

```text
전체 문제 P(N)
   │
   ▼
1. 종료 조건 판정 (N ≤ Base Case Threshold)
├─ 참 (기저 도달): 기저 해 직접 계산 후 즉시 반환 ($O(1)$)
└─ 거짓 (분할 가능)
   │
   ▼
2. 부분 문제 분할 (N ──► N/2, N/2)
   │
   ▼
3. 부분 문제 재귀 정복 (T(N/2) 각각 독립 실행)
   │
   ▼
4. 부분 해 결합 (Combine Partial Solutions)
   │
   ▼
최종 해 반환
```

**동작 원리**

1. **종료 조건 판정**: 현재 입력 크기가 기저 조건에 도달했는지 확인
2. **기저 해 계산**: 최소 문제 크기이면 재귀 없이 답을 즉시 계산하여 상위로 반환
3. **부분 문제 분할**: 최소 문제가 아니면 입력을 독립적인 작은 부분 문제들로 분할
4. **부분 문제 재귀 해결**: 각 부분 문제에 대해 재귀 호출을 수행하여 독립적으로 부분 해 도출
5. **부분 해 결합**: 반환된 하위 부분 해들을 결합 규칙(예: Merge)에 따라 병합하여 상위 문제의 해 구축

#### 한줄 요약

- 종료 조건까지 분할하고, 재귀에서 복귀하며 부분 해를 상위 해로 결합

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Divide and Conquer vs Dynamic Programming**:
  - 분할 정복: 부분 문제들이 서로 독립적(중복 없음), 재귀적 분할-결합, 병합 정렬/퀵 정렬.
  - 동적 계획법: 부분 문제들이 심하게 중복됨(Overlapping), 상태 캐싱(Memoization), 최적 부분 구조.

</details>

| 비교 항목 | 분할 정복 (Divide & Conquer) | 동적 계획법 (Dynamic Programming) |
|:---|:---|:---|
| 적용 기준 | **독립 부분 문제** 분할 및 결합 가능 시 | 동일한 **중복 부분 문제**가 빈번히 재출현 시 |
| 핵심 특징 | **분할•정복•결합**의 하향식 재귀 구조 | 하위 상태값을 **DP 캐시 테이블**에 저장 및 재사용 |
| 한계 및 위험 | 피벗 불균형 시 최악 $O(n^2)$ 선형 퇴화 | 상태 차원 증가 시 **공간복잡도(Memory)** 급증 |

#### 한줄 요약

- 중복 부분 문제가 없으면 분할 정복(D&C), 동일 서브문제가 무수히 재출현하면 DP(Memoization)를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **제자리 결합(In-Place Merge)**: 추가적인 대규모 보조 배열 할당 없이 기존 버퍼 내에서 포인터 스왑으로 데이터를 병합하는 기법.
- **임계값 기반 하이브리드 전환**: 재귀 호출 깊이가 깊어지거나 크기가 작아질 때(예: $N \le 16$) 삽입 정렬 등으로 전환하는 기법(Timsort).

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **불균형 분할**로 호출 깊이•최악 시간이 선형 퇴화 | 균형 분할(중간값 피벗)과 **재귀 깊이 제한** 적용 | 재귀 깊이와 최악 수행시간 통제 |
| 작은 부분 문제에서 재귀 호출 비용이 계산량 초과 | **임계 크기($N \le 16$)**부터 반복 알고리즘 전환 | 작은 입력의 **호출 오버헤드** 대폭 감소 |
| 높은 **결합 비용**으로 공간•복사량이 분할 이득 상쇄 | 버퍼 재사용 또는 **제자리 결합(In-place)** 적용 | 결합 단계의 추가 공간•복사량 감소 |
| 병렬 작업 크기 편차로 처리 장치 유휴•꼬리 지연 | Fork-Join 프레임워크 및 **동적 작업 훔치기(Work-Stealing)** | 코어 간 **부하 균형(Load Balancing)** 극대화 |

#### 한줄 요약

- **임계값 하이브리드 전환·In-Place 결합 최적화·Work-Stealing 병렬화**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **분할 정복 적용 타당성**: 분할 및 결합에 소요되는 총비용이 전체 병렬화 및 점근적 시간 단축 이득보다 작을 때 성립하는 설계 판단.

</details>

- 독립적 부분 문제는 **분할 정복**, 중복 부분 문제와 최적화는 **동적 계획법** 선택

#### 한줄 요약

- 분할•결합 비용이 병렬 이득보다 작을 때 적용하고, 작은 문제는 반복 방식으로 전환
