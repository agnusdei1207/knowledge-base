## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **알고리즘적 계산 가능성(Computability)**: 어떤 수학적 문제가 유한한 시간 내에 기계적 전이 규칙으로 해를 도출할 수 있는지 여부를 판별하는 계산 이론적 한계.
- **정지 문제(Halting Problem)**: 임의의 프로그램과 입력이 주어졌을 때 해당 프로그램이 종료될지 무한 루프에 빠질지를 판별하는 범용 알고리즘이 존재할 수 없음을 증명한 결정 불가능 문제.

</details>

- 정의/개념: 무한 테이프와 상태 전이 함수($\delta$)를 통해 **알고리즘적 계산 가능성**의 수학적 한계를 형식화한 추상 오토마타 모델
- 배경/필요성: 유한 상태 및 스택 메모리 제약으로 인해 범용 알고리즘의 본질적 계산 가능성과 정지 문제의 결정 불가능성을 증명할 수 없던 추상 계산 모델 한계

#### 한줄 요약

- 계산을 빠르게 하려는 모델이 아니라 무엇이 계산 불가능한지를 그어 보이려는 모델이므로, 산출물은 효율이 아니라 가능성의 경계이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **튜링 완전성(Turing Completeness)**: 어떤 프로그래밍 언어나 가상 머신이 범용 튜링 머신과 동일한 계산 능력을 보유하고 있음을 의미하는 성질.
- **범용 튜링 머신(Universal Turing Machine, UTM)**: 다른 튜링 머신의 프로그램 코드(전이 함수 설명)와 입력을 테이프에 적재하여 이를 모사 실행하는 현대 폰 노이만 컴퓨터의 원형 모델.

</details>

- 무한 테이프와 상태 제어로 컴퓨터의 모든 계산을 모사하는 **튜링 완전성**
- 다중 테이프 등 모든 확장 모델이 단일 테이프 TM과 **계산 능력 면에서 등가**
- 대각선 논법을 통해 증명된 **정지 문제의 결정 불가능성**

#### 한줄 요약

- 처치-튜링 명제에 따라 다중 테이프 및 비결정적 튜링 머신의 계산 능력은 단일 테이프 결정적 튜링 머신과 등가이며, 정지 문제로 판정 불능성을 입증한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **튜링 머신 7-튜플 모델($M = (Q, \Sigma, \Gamma, \delta, q_0, q_{accept}, q_{reject})$)**: 상태 집합 $Q$, 입력 알파벳 $\Sigma$, 테이프 알파벳 $\Gamma$, 전이 함수 $\delta$, 시작 상태 $q_0$, 수용/거부 상태 $q_{accept}, q_{reject}$로 정의되는 수학적 기계.

</details>

```text
+--------------------------------------------------------+
|                    튜링 머신 (TM)                      |
|  - 7-튜플 M = (Q, Σ, Γ, δ, q0, qacc, qrej) 계산 모델   |
+---------------------------+----------------------------+
                            |
            +---------------+---------------+
            v                               v
+-----------------------+       +-----------------------+
|      상태 제어부      |       |      R/W 헤드         |
|  - Q: 내부 상태 집합  |       |  - 현재 셀 기호 읽기  |
|  - δ: 전이 함수 모듈  |       |  - 심볼 기록 및 L/R   |
+-----------+-----------+       +-----------+-----------+
            |                               |
            +---------------+---------------+
                            v
+--------------------------------------------------------+
|                       무한 테이프                      |
|  - 양방향 무한 메모리 공간 및 셀 단위 기호(Γ) 보관     |
+--------------------------------------------------------+
```

선의 의미: 실선 박스는 튜링 머신 구성 요소, 화살표(->)는 상태 전이에 따른 헤드 제어 및 테이프 입출력 흐름

| 구성요소 | 책임 |
|:---|:---|
| 상태 제어부 | 시작·현재·수용·거부 상태 유지 |
| 전이 함수 $\delta$ | 현재 상태와 테이프 기호에 따라 **다음 상태·기록 기호·이동 방향** 결정 |
| R/W 헤드 | 현재 테이프 셀의 기호 **읽기·쓰기 및 좌·우(L/R) 이동** 수행 |
| 무한 테이프 | 입력 데이터 및 중간 계산 결과를 저장하는 **무한 길이의 메모리** |

#### 한줄 요약

- 상태 제어부와 전이 함수가 다음 행동을 정하고, 헤드가 테이프의 기호를 바꾸며 좌우로 이동한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **정지 상태(Halting State)**: 전이 함수에 의해 $q_{accept}$ 또는 $q_{reject}$ 상태에 도달하여 머신의 연산이 완전히 멈추는 상태.

</details>

```text
+------------------------------------------+
|  입력 문자열 W 가 테이프에 배치됨 (q0)   |
+--------------------+---------------------+
                     |
                     v
+------------------------------------------+
|  1. 헤드 위치의 현재 테이프 기호 a 읽기  |
+--------------------+---------------------+
                     |
                     v
           /--------------------\
          <  전이 규칙 δ(q, a)? >
           \--------------------/
            |                  |
   정의됨   |                  | 미정의
 (p, b, D)  v                  v
[ 테이프에 b 기록 및 D 이동 ] [ 이상 거부 정지 (Reject) ]
            |
            v
     /--------------\
    <  도달 상태 q?  >
     \--------------/
      |            |           |
  q_accept     q_reject    일반 상태
      v            v           v
  [ Accept ]   [ Reject ]  [ 1. 기호 읽기로 루프 반복 ]
```

분기 결과: 전이 함수가 미정의되었거나 $q_{reject}$ 상태에 도달하면 입력을 거부(Reject)하고 계산을 종료하며, $q_{accept}$ 상태에 도달하면 입력을 수용(Accept)하고, 일반 상태인 경우 테이프 갱신 및 헤드 이동 후 다음 스텝 루프를 반복한다.

**동작 원리**:
1. **기호 판독**: R/W 헤드가 위치한 무한 테이프의 현재 셀에서 테이프 알파벳 기호 $a \in \Gamma$를 읽어들인다.
2. **전이 규칙 조회**: 현재 내부 상태 $q$와 판독 기호 $a$를 인자로 전이 함수 $\delta(q, a)$를 조회하여 다음 상태 $p$, 기록할 기호 $b$, 헤드 이동 방향 $D \in \{L, R\}$를 결정한다.
3. **셀 기록 및 헤드 이동**: 현재 테이프 셀에 새 기호 $b$를 덮어쓰고, 지정된 방향($D$)에 따라 헤드를 좌측 또는 우측으로 정확히 1칸 이동한다.
4. **내부 상태 갱신**: 제어부의 현재 상태를 $p$로 갱신하고 정지 상태 도달 여부를 확인한다.
5. **정지 및 결과 판정**: 갱신된 상태가 $q_{accept}$이면 계산 수용으로 정지하고, $q_{reject}$이거나 규칙이 없으면 계산 거부로 정지하며, 일반 상태인 경우 1단계로 복귀하여 계산 루프를 지속한다.

#### 한줄 요약

- 언제 멈출지가 전이 규칙 안에 들어 있지 않고 실행해 봐야만 드러나므로, 이 루프의 종료 여부를 밖에서 미리 답할 수 없다는 것이 곧 정지 문제이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **튜링 머신(Turing Machine, TM)**: 무한 양방향 테이프를 사용하여 0형식 무제약 언어를 인식하는 범용 계산 모델.
- **푸시다운 오토마타(Pushdown Automaton, PDA)**: LIFO 스택 메모리를 사용하여 2형식 문맥 자유 문법을 인식하는 모델.
- **유한 오토마타(Finite Automaton, FA)**: 추가 메모리 없이 유한 상태 전이만으로 3형식 정규 언어를 인식하는 모델.

</details>

| 계산 모델 | 튜링 머신 (TM) | 푸시다운 오토마타 (PDA) | 유한 오토마타 (FA / DFA) |
|:---|:---|:---|:---|
| 적용 기준 | **범용 계산 모델링** 및 튜링 완전성 검증 | 수식, 괄호 짝 등 **재귀 중첩 구문** 파싱 | 어휘 분석 및 **정규 토큰 매칭** |
| 핵심 특징 | **무한 양방향 테이프** 기반 0형식 언어 인식 | **LIFO 푸시다운 스택** 기반 2형식 문맥 자유 언어 | **유한 상태** 전이 기반 3형식 정규 언어 인식 |
| 한계 | **정지 문제** 판정 불가 | 문맥 의존 언어($a^n b^n c^n$) 인식 불가 | 임의 깊이의 중첩 괄호 인식 불가 |

#### 한줄 요약

- 정규 언어는 유한 상태, 중첩 구문은 스택, 범용 계산은 읽기•쓰기 테이프를 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **스마트 컨트랙트 가스(Gas) 시스템**: 튜링 완전 블록체인에서 무한 루프에 의한 노드 정지를 방지하기 위해 명령어당 실행 비용(Gas)을 부과하고 한도 초과 시 강제 종료하는 메커니즘.
- **메모리 부족 킬러(Out-of-Memory Killer, OOM Killer)**: OS가 가용 물리 메모리와 스왑 공간을 모두 소진했을 때 프로세스를 강제 종료하여 커널 패닉을 방지하는 메모리 보호 기제.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프로그램의 **정지 여부 판정 불가** | 최대 실행 시간 및 **명령어 스텝 수 제한** 강제 | 시스템의 **무한 실행 차단** |
| 블록체인 튜링 완전 코드의 **노드 자원 고갈 공격** | **가스(Gas) 시스템** 도입 및 상한선(Gas Limit) 설정 | DoS 공격 차단 및 자원 과금 실현 |
| 튜링 완전 스크립트 실행 시 **호스트 시스템 침해 위험** | Wasm/gVisor 기반 **샌드박스 격리 및 syscall 제한** | 시스템 커널 접근 원천 차단 |
| 무한 테이프 추상화와 실제 물리 메모리 간 불일치 | 가상 메모리 스왑 및 **OOM 킬러** 연동 | OS 메모리 고갈 크래시 방지 |

#### 한줄 요약

- 무한 루프는 Gas Limit이나 타임아웃으로 강제 종료하고, 임의 코드 실행은 샌드박스로 격리하며, 메모리 소진은 OOM 한도로 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **현대 컴퓨터 공학의 초석**: 튜링 머신은 단순한 이론적 기계를 넘어 폰 노이만 구조, 프로그래밍 언어 이론, 가상화 샌드박스, 계산 복잡도 이론의 수학적 근간으로 기능.

</details>

- 폰 노이만 컴퓨터 아키텍처, 프로그래밍 언어의 튜링 완전성 및 계산 복잡도 이론의 근본 수학적 모델로 정립되어 널리 활용되고 있으며, 향후 양자 튜링 머신 및 신경망 기반 신경 튜링 머신(NTM) 등 신개념 하이브리드 계산 구조로 확장될 것으로 전망되고, 실무 엔지니어링에서는 정지 문제로 인한 무한 루프 위험을 차단하기 위해 블록체인 가스(Gas Limit) 시스템, 실행 시간·명령어 상한(Timeout) 및 Wasm/eBPF 기반 샌드박스 격리 체계를 강제해야 한다.

#### 한줄 요약

- 범용 계산은 샌드박스에서 실행하고 시간•메모리•입출력 권한 한도를 강제한다.
