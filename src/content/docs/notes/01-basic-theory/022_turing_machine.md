## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **튜링 머신(Turing Machine)**: 무한 테이프의 기호를 읽고 쓰는 헤드와 상태 전이 규칙으로 계산을 표현하는 추상 기계
- **계산 가능성**: 주어진 문제를 유한한 알고리즘 절차로 해결할 수 있는 성질
- **추상 계산 모델**: 실제 하드웨어와 무관하게 계산 절차와 한계를 수학적으로 표현한 모델

</details>

- 정의/개념: **튜링 머신** 은 무한 테이프의 기호를 읽고 쓰는 헤드와 상태 전이로 연산을 표현하는 **추상 계산 모델**
- 배경/필요성: 알고리즘의 **계산 가능 범위** 를 공통 모델로 정의

#### 한줄 요약

- 끝없이 이어진 종이띠의 한 칸을 읽고 고쳐 쓴 뒤 좌우로 움직이는 기계만으로, 어떤 계산을 절차로 수행할 수 있는지 정의한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **튜링 완전(Turing Complete)**: 충분한 시간과 메모리가 있으면 튜링 머신의 모든 계산을 모사할 수 있는 성질
- **정지 문제(Halting Problem)**: 임의 프로그램이 입력에서 정지하는지를 모든 경우에 판정할 수 없는 문제
- **결정 가능 언어**: 모든 입력에서 정지하며 소속 여부를 판정할 수 있는 언어
- **테이프(Tape)**: 기호를 읽고 쓸 수 있는 칸이 양방향으로 이어진 튜링 머신의 기억장치
- **비결정성**: 한 상태와 입력에서 가능한 다음 동작이 여러 개인 계산 모델의 성질

</details>

- 유한 제어부와 무한 **테이프** 로 범용 계산을 모사하는 **튜링 완전성**
- 다중 테이프•비결정성 변형과 **계산 가능 범위** 동일
- **결정 가능** 범위 밖에는 **정지 문제** 같은 판정 불가 문제 존재

#### 한줄 요약

- 종이띠나 선택 갈래를 늘려도 계산 가능 범위는 같고, 모든 프로그램의 정지를 판정하는 기계는 만들 수 없다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **전이 함수 $\delta$**: 현재 상태와 읽은 기호로 다음 상태•기록 기호•이동 방향을 결정하는 함수
- **헤드(Head)**: 현재 테이프 칸을 읽고 쓰며 좌우로 이동하는 장치
- **테이프 알파벳 $\Gamma$**: 테이프에 기록할 수 있는 모든 기호의 집합
- **정지 상태(Halting State)**: 계산을 끝내고 입력의 수용이나 거부를 확정하는 상태
- **상태 제어부**: 시작 상태에서 현재 상태를 유지하고 수용•거부 상태 도달을 판정하는 부분

</details>

```mermaid
block-beta
    columns 3
    S["상태 제어부"] --- T["전이 함수"] --- H["헤드"] --- P["테이프"]
```

| 구성요소 | 책임 |
|:---|:---|
| 상태 제어부 | 시작•현재•**수용•거부 상태** 유지 |
| 전이 함수 | 상태•읽은 기호로 **다음 행동** 결정 |
| 헤드 | 현재 칸 읽기•쓰기와 **좌우 이동** 수행 |
| 테이프 | **테이프 알파벳** 기호의 무한 저장 공간 |

#### 한줄 요약

- 상태 제어부와 전이 함수가 다음 행동을 정하고, 헤드가 테이프의 기호를 바꾸며 좌우로 이동한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **현재 기호**: 헤드가 위치한 테이프 칸에 기록된 기호
- **기록 지시**: 현재 테이프 칸에 쓸 기호를 지정한 전이 결과
- **이동 지시**: 헤드가 움직일 좌우 방향을 지정한 전이 결과

</details>

```mermaid
sequenceDiagram
    participant S as 상태 제어부
    participant T as 전이 함수
    participant H as 헤드
    participant P as 테이프
    S->>H: 실행 시작
    loop 정지 상태가 아닐 동안
        H->>P: 1. 현재 기호 요청
        P-->>H: 현재 기호 반환
        S->>T: 현재 상태 전달
        H->>T: 2. 읽은 기호 전달
        T->>H: 3. 기록•이동 지시 전달
        H->>P: 갱신 기호 전달
        T->>S: 4. 다음 상태 전달
    end
    S->>S: 수용•거부 확정
```

### 동작 원리

- **1. 현재 기호 요청**: 헤드 위치의 기호 확인
- **2. 읽은 기호 전달**: 현재 상태와 함께 전이 입력 구성
- **3. 기록•이동 지시 전달**: 기호 기록 후 헤드 이동
- **4. 다음 상태 전달**: 상태 변경•정지 여부 판정

#### 한줄 요약

- 기계가 종이띠 한 칸을 읽으면 전이표가 새 기호•헤드 이동 방향•다음 상태를 한꺼번에 지시하고, 정지 상태까지 같은 순서를 반복한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **유한 오토마타(Finite Automaton, FA)**: 별도 기억장치 없이 유한 상태만으로 정규 언어를 인식하는 모델
- **푸시다운 오토마타(Pushdown Automaton, PDA)**: 스택을 사용해 중첩 구조를 포함한 문맥 자유 언어를 인식하는 모델

</details>

| 계산 모델 | 튜링 머신 | 푸시다운 오토마타 | 유한 오토마타 |
|:---|:---|:---|:---|
| 적용 기준 | **계산 가능성** 분석 | 괄호•블록 등 **중첩 구문** | 토큰•**제어 상태** 판별 |
| 핵심 특징 | **무한 테이프** 양방향 읽기•쓰기 | **스택 최상단** 만 접근 | **유한 상태** 만 유지 |
| 한계 | **정지 문제** 판정 불가 | **문맥 의존** 언어 인식 불가 | 기억 장치 부재로 **재귀 구조** 미인식 |

#### 한줄 요약

- 유한 오토마타는 머릿속 상태만, 푸시다운 오토마타는 접시 더미 같은 스택까지, 튜링 머신은 양방향 종이띠까지 기억에 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **튜링 인식 가능 언어**: 소속 입력은 정지해 수용하지만 비소속 입력에서는 멈추지 않을 수 있는 언어
- **샌드박스(Sandbox)**: 실행 시간•메모리•입출력 권한을 제한해 프로그램을 격리하는 환경
- **초과 정책**: 프로그램이 단계 수나 메모리 상한을 넘었을 때 중단•실패로 처리하는 운영 규칙
- **단계 수 제한**: 계산이 수행할 수 있는 전이 횟수에 둔 운영 상한
- **입출력 권한**: 프로그램이 접근할 수 있는 파일•장치•통신 범위를 정한 허용 규칙

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 프로그램 **정지 여부** 사전 판정 불가 | 실행 시간•**단계 수 제한** | **무한 실행** 차단 |
| 무한 테이프와 **실제 메모리** 차이 | 메모리 상한•**초과 정책** 정의 | **자원 고갈** 방지 |
| **인식•결정 가능** 혼동 | 비소속 입력의 **정지 여부** 증명 | **계산 가능성 분류** 정확화 |
| 범용 계산의 **권한 남용** | 샌드박스•**입출력 권한** 최소화 | 시스템 **영향 범위** 격리 |

#### 한줄 요약

- 언제 멈출지 미리 알 수 없는 프로그램을 격리실에 넣듯, 실행 단계•메모리•입출력 권한에 상한을 두어 무한 실행과 자원 고갈을 가둔다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **운영 한계**: 범용 계산 실행에 허용하는 시간•메모리•권한의 최대 범위

</details>

- 정규 패턴은 **FA**, 중첩은 **PDA**, 범용 계산은 튜링 머신 선택

#### 한줄 요약

- 어떤 계산도 표현할 수 있는 범용 기계를 실제로 실행할 때는 타이머•메모리 벽•권한 울타리로 운영 한계를 강제한다.
