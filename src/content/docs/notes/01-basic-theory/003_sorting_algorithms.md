## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **정렬 알고리즘(Sorting Algorithm)**: 원소들을 지정된 키 순서로 재배열하여 후속 탐색 및 병합 처리 효율을 높임.
- **키(Key)**: 레코드 간 정렬 순서를 판단하고 비교하는 기준값.

</details>

- 정의/개념: 지정된 키 비교 및 변환 규칙에 따라 데이터를 순서대로 재배열하는 **정렬 알고리즘 메커니즘**
- 배경/필요성: 미정렬 데이터의 반복 비교 비용을 줄이고 탐색·병합 등 후속 연산 효율을 극대화하기 위한 정렬 필요성

#### 한줄 요약

- 데이터를 키 순으로 사전 정렬하여 탐색복잡도를 단축시키고 이진 탐색 및 병합 연산의 효율을 극대화한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **비교 정렬(Comparison Sort)**: 키 대소 비교 연산 결과만으로 순서를 결정하는 정렬 기법.
- **비교 정렬 하한(Lower Bound of Comparison Sort, $\Omega(n\log n)$)**: 비교 기반 정렬이 도달할 수 있는 이론적 최악 성능 한계.
- **안정 정렬(Stable Sort)**: 동등한 키를 가진 원소들의 초기 입력 순서를 정렬 완료 후에도 유지함.
- **제자리 정렬(In-Place Sort)**: $O(1)$ 수준의 보조 공간만을 사용하여 원본 데이터 배열 내에서 재배열을 완료함.
- **보조 공간(Auxiliary Space)**: 입력 데이터 수용 이외에 정렬 수행 중 추가로 할당되는 메모리.
- **평균 시간복잡도(Average Time Complexity)**: 일반적 입력 분포에서 기대되는 연산 증가율.
- **최악 시간복잡도(Worst-case Time Complexity)**: 가장 불리한 입력 구성에서의 최악 연산 증가율.

</details>

![효율적 비교 정렬과 제곱 시간 정렬의 증가율](/study/diagrams/sorting-comparison-growth.svg)

> 입력 규모 증가에 따라 O(n²) 연산량이 O(n log n) 대비 급격히 발산하는 비선형 성장 양상

- 비교 정렬 알고리즘의 이론적 성능 **하한 $\Omega(n\log n)$** 준수
- 알고리즘별 **평균·최악 시간복잡도** 특성 평가 및 세분화
- **안정성 및 제자리 정렬** 여부에 따른 메모리 및 순서 보존 제약 고려

#### 한줄 요약

- 비교 기반 정렬의 이론적 하한인 $\Omega(n \log n)$을 준수하며, 단순 $O(n^2)$ 정렬 대비 대용량 처리 시 연산 효율성을 보장한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **정렬 제어기(Sort Controller)**: 정렬 대상 구간 관리 및 재귀·반복 제어 흐름을 전담함.
- **비교 함수(Comparator)**: 두 원소의 키를 비교하여 대소 및 동등 관계를 판정함.
- **재배열 전략(Rearrangement Strategy)**: 비교 결과에 따른 분할, 교환, 병합 데이터 이동 수행.

</details>

```text
정렬 알고리즘 구조
├─ 정렬 제어기
├─ 비교 함수
├─ 재배열 전략
└─ 보조 공간
```

가지의 의미: 정렬 시스템의 정적 책임 분할 구성 요소

| 구성요소 | 책임 |
|:---|:---|
| 계산 모델 | **기본 연산**의 단위 비용 규정 |
| 정렬 제어기 | **정렬 제어기**가 미정렬 구간과 처리 순서 관리 |
| 비교 함수 | **비교 함수**가 두 키의 대소•동등 관계 판정 |
| 재배열 전략 | **재배열 전략**으로 분할•병합•교환 수행 |
| 보조 공간 | **보조 공간**에 임시 배열•재귀 상태 보관 |

#### 한줄 요약

- 스케줄러(제어기), 비교 연산자(비교 함수), 데이터 이동기(재배열), 보조 공간의 4가지 핵심 구조로 분리되어 수행된다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **입력 규모(Input Scale)**: 인메모리 처리와 외부 정렬 방식을 가르는 데이터 크기.
- **선택 우선순위(Selection Priority)**: 시간, 공간, 안정성, 최악 상한 간 최우선 고려 조건.
- **최악 상한(Worst-case Upper Bound)**: 가장 불리한 입력에서도 초과하지 않는 실질 수행시간 한계.

</details>

```text
정렬 방식 선택
├─ 메모리 초과
│  └─ 외부 병합 정렬
└─ 메모리 내 처리
   ├─ 안정성 필요
   │  └─ 병합 정렬
   ├─ 최악 상한•공간 제한
   │  └─ 힙 정렬
   ├─ 거의 정렬된 소규모 입력
   │  └─ 버블 정렬
   └─ 평균 속도 우선
      └─ 퀵 정렬
```

가지의 의미: 입력 제약 및 품질 보장 조건에 따른 선택 결정 분기 구조

#### 한줄 요약

- 데이터의 규모(In-Memory/External), 안정성(Stability) 필요 여부, 메모리 제약 및 최악 시간 복잡도 보장 조건을 기준으로 정렬 알고리즘을 결정한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **퀵 정렬(Quick Sort)**: 피벗 기반 분할 후 좌우 구간을 독립 재귀 정렬함.
- **병합 정렬(Merge Sort)**: 데이터를 반으로 분할 정렬 후 순서대로 합치는 분할 정복 기반 안정 정렬.
- **힙 정렬(Heap Sort)**: 완전이진트리 기반 최대 힙에서 루트 노드를 반복 추출하여 제자리 정렬을 완료함.
- **버블 정렬(Bubble Sort)**: 인접 원소 간 대소를 비교하여 역순일 때 반복 교환하는 단순 정렬.
- **피벗(Pivot)**: 퀵 정렬에서 기준이 되어 데이터를 좌우로 분할하는 비교 값.
- **캐시 지역성(Cache Locality)**: 인접 메모리 공간의 연속적 접근을 통해 캐시 적중률을 높임.
- **제곱 시간복잡도(Quadratic Time Complexity)**: 입력 크기의 제곱에 비례하여 연산 소모가 증폭되는 $O(n^2)$ 차수.

</details>

| 정렬 알고리즘 | 퀵 | 병합 | 힙 | 버블 |
|:---|:---|:---|:---|:---|
| 적용 기준 | 메모리 내 배열•**평균 시간복잡도** | **안정성**•외부 정렬 | **최악 상한**•공간 제한 | 거의 정렬된 소규모 입력 |
| 핵심 특징 | **피벗 분할**•제자리 정렬 | 순차 **분할•병합** | **최대 힙** 반복 추출 | 인접 **역순 교환** |
| 한계 | 불균형 시 **제곱 시간복잡도** | 입력 크기의 **보조 공간** | 불안정•낮은 **캐시 지역성** | 평균•최악 **제곱 시간복잡도** |

> 요약: 수행 속도, 메모리 제약, 안정성, 최악 상한 보장 요구 조건에 따른 차별적 정렬 알고리즘 선택

#### 한줄 요약

- 빠른 평균 처리에는 퀵, 같은 키 순서 보존에는 병합, 최악 시간 보장에는 힙, 거의 정렬된 소량 데이터에는 버블을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **외부 정렬(External Sorting)**: 주기억장치 용량을 초과하는 대용량 데이터를 블록 단위로 나누어 디스크 기반으로 병합함.
- **불균형 분할(Unbalanced Partition)**: 피벗 편향으로 인해 퀵 정렬의 재귀 깊이가 $O(n)$으로 심화되는 현상.
- **무작위 피벗(Random Pivot)**: 최악 분할 패턴 발생을 방지하기 위해 임의의 원소를 피벗으로 추출함.
- **키 사전 계산(Key Precomputation)**: 반복적인 키 평가 연산 부하를 차단하기 위해 정렬 키를 미리 계산 및 저장함.
- **외부 병합(External Merge)**: 디스크에 분할 정렬되어 저장된 파일 블록(Run)들을 스트리밍 순차 병합함.
- **비교 비용(Comparison Cost)**: 키 간 대소 관계를 판정하는 데 필요한 단위 산술 연산 소모량.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 메모리보다 큰 **입력 규모**로 인메모리 정렬 중 고갈 | 구간 정렬 후 **외부 병합** 적용 | 제한 메모리에서 **외부 정렬** 완주 |
| 동일 키의 입력 순서가 불안정 정렬로 변경 | 순서 보존 요구 시 **안정 정렬** 선택 | 연관 레코드의 **안정성** 보존 |
| 퀵 정렬의 **불균형 분할**로 최악 $O(n^2)$ 퇴화 | 무작위 피벗과 깊이 한계 이후 힙 정렬 전환 | 재귀 깊이와 **최악 상한** 통제 |
| 객체의 높은 **비교 비용**으로 키 계산 지연 누적 | **키 사전 계산**과 참조 기반 재배열 적용 | 반복 비교 비용 감소 |

#### 한줄 요약

- 주기억장치 용량을 초과하는 데이터셋은 런(Run) 단위 분할 정렬 후 외부 병합(External Merge Sort) 방식을 적용한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **안정성(Stability)**: 동일한 키 값을 가진 원소들의 초기 상대적 위치 관계를 정렬 후에도 보존하는 특성.

</details>

- 가용 메모리 한계, 데이터 안정성 요구, 최악 시간 보장 제약 조건 종합 검토를 통한 최적 정렬 알고리즘 최종 결정

#### 한줄 요약

- 데이터의 가용 메모리 초과 여부, 키 순서 보존(Stability) 요권, 최악 수행 시간 보장성에 맞춰 최적 정렬 알고리즘을 선별한다.
