## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **키 대소 비교 규칙(Key Comparison Rule)**: 정렬 대상 원소 간의 우선순위를 결정하기 위해 정의된 전순서(Total Order) 비교 기준.
- **데이터베이스 인덱싱(Database Indexing)**: 대량의 레코드를 B-Tree 등의 정렬된 구조로 유지하여 검색 성능을 극대화하는 색인 기술.

</details>

- 정의/개념: 지정된 **키 대소 비교 규칙**에 따라 원소들을 순서대로 재배치하는 데이터 정렬 알고리즘
- 배경/필요성: 비정렬 상태에서는 **이진 탐색** 및 순차 병합 처리 불가

#### 한줄 요약

- 데이터를 키 순서로 배치하면 이진 탐색과 순차 병합을 적용할 수 있다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **비교 정렬(Comparison Sort)**: 키 대소 비교 연산 결과만으로 순서를 결정하는 정렬 기법.
- **비교 정렬 하한(Lower Bound of Comparison Sort, $\Omega(n\log n)$)**: 비교 기반 정렬이 도달할 수 있는 이론적 최악 성능 한계.
- **안정 정렬(Stable Sort)**: 동등한 키를 가진 원소들의 초기 입력 순서를 정렬 완료 후에도 유지하는 성질.
- **제자리 정렬(In-Place Sort)**: $O(1)$ 수준의 보조 공간만을 사용하여 원본 데이터 배열 내에서 재배열을 완료하는 기법.
- **보조 공간(Auxiliary Space)**: 입력 데이터 수용 이외에 정렬 수행 중 추가로 할당되는 메모리.
- **평균 시간복잡도(Average Time Complexity)**: 일반적 입력 분포에서 기대되는 연산 증가율.
- **최악 시간복잡도(Worst-case Time Complexity)**: 가장 불리한 입력 구성에서의 최악 연산 증가율.

</details>

![효율적 비교 정렬과 제곱 시간 정렬의 증가율](/study/diagrams/sorting-comparison-growth.svg)

> 입력 규모 증가에 따라 O(n²) 연산량이 O(n log n) 대비 급격히 발산하는 비선형 성장 양상

- 비교 정렬의 최악 비교 횟수는 결정 트리 기반 **비교 정렬 하한**($\Omega(n\log n)$) 준수
- **평균 시간복잡도** 및 **최악 시간복잡도**를 분리하여 실행 환경별 맞춤형 전략 적용
- **안정 정렬** 및 **제자리 정렬** 특성을 고려해 순서 보존 및 메모리 제약 대응

#### 한줄 요약

- 비교 정렬은 안정성·보조 공간·최악 시간 중 필요한 조건에 따라 선택이 달라진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **기본 연산(Basic Operation)**: 키 대소 비교 및 원소 교환 등 정렬 시간 비용을 결정하는 단위 연산.
- **비교 함수(Comparator)**: 두 원소의 키를 비교하여 대소 및 동등 관계를 판정하는 함수.

</details>

```text
[ 정렬 알고리즘 내부 구조 및 책임 분할 ]
┌──────────────────────────────┐
│ 제어 흐름 (Control Flow)     │ ── 미정렬 구간 분할 및 반복/재귀 호출 통제
├──────────────────────────────┤
│ 비교 함수 (Comparator)       │ ── 두 키(Key)의 대소 및 동등 관계 판정
├──────────────────────────────┤
│ 데이터 이동 (Data Movement)  │ ── 분할, 병합, 스왑(Swap) 기반 위치 변경
├──────────────────────────────┤
│ 보조 공간 (Auxiliary Memory) │ ── 임시 버퍼 및 호출 스택 메모리 관리
└──────────────────────────────┘
```

선의 의미: 제어 흐름, 비교 판정, 데이터 이동 및 보조 메모리 관리 간의 정렬 아키텍처 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 제어 흐름 | 미정렬 구간과 재귀·반복 처리 순서 관리 |
| 비교 함수 | 두 키의 대소·동등 관계를 판정하는 **비교 함수** |
| 데이터 이동 | 비교 결과에 따른 분할·병합·교환 수행 |
| 보조 공간 | 임시 배열 및 재귀 상태를 보관하는 **보조 공간** |

#### 한줄 요약

- 제어 흐름이 비교 결과에 따라 데이터를 옮기며 필요하면 보조 공간에 상태를 보관한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **외부 정렬(External Sorting)**: 메모리 용량을 초과하는 대용량 데이터를 블록 단위로 나누어 디스크 기반으로 정렬·병합하는 기법.
- **최악 상한(Worst-case Upper Bound)**: 가장 불리한 입력에서도 초과하지 않는 실질 수행시간 한계.

</details>

```text
정렬 방식 선택
├─ 메모리 초과
│  └─ 외부 병합 정렬
└─ 메모리 내 처리
    ├─ 안정성 필요
    │  └─ 병합 정렬
    ├─ 최악 상한•공간 제한
    │  └─ 힙 정렬
    ├─ 구현 단순성•교육 목적
    │  └─ 버블 정렬
    └─ 평균 속도 우선
        └─ 퀵 정렬
```

선의 의미: 가지(`├─`, `└─`)는 입력 제약 및 품질 보장 조건에 따른 정렬 방식 선택 결정 분기

**선택 원리**

- 가용 메모리를 초과하면 청크 기반 **외부 정렬** 선택
- 다중 키의 상대 순서 보존이 필요하면 **병합 정렬** 선택
- 제자리 공간과 최악 상한이 필요하면 **힙 정렬** 선택
- 평균 속도와 캐시 지역성이 우선이면 **퀵 정렬** 선택

#### 한줄 요약

- 데이터 규모·안정성·메모리·최악 시간 조건을 차례로 확인해 정렬 방식을 고른다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **퀵 정렬(Quick Sort)**: 피벗 기반 분할 후 좌우 구간을 독립 재귀 정렬하는 제자리 알고리즘.
- **병합 정렬(Merge Sort)**: 데이터를 반으로 분할 정렬 후 순서대로 합치는 분할 정복 기반 안정 정렬.
- **힙 정렬(Heap Sort)**: 완전이진트리 기반 최대 힙에서 루트 노드를 반복 추출하여 제자리 정렬을 완료하는 알고리즘.
- **버블 정렬(Bubble Sort)**: 인접 원소 간 대소를 비교하여 역순일 때 반복 교환하는 단순 정렬.
- **피벗(Pivot)**: 퀵 정렬에서 배열을 두 부분으로 분할하기 위해 기준점으로 선택하는 원소.
- **최대 힙(Max Heap)**: 부모 노드의 키가 자식 노드의 키보다 항상 크거나 같은 완전이진트리 자료구조.
- **캐시 지역성(Cache Locality)**: 최근 참조한 메모리 주소나 인접 주소를 다시 참조할 확률이 높아 CPU 캐시 적중률을 높이는 특성.

</details>

| 정렬 알고리즘 | 퀵 정렬 (Quick Sort) | 병합 정렬 (Merge Sort) | 힙 정렬 (Heap Sort) | 버블 정렬 (Bubble Sort) |
|:---|:---|:---|:---|:---|
| 적용 기준 | 메모리 내 배열 및 **평균 시간복잡도** 최우선 | **안정 정렬** 필수 및 대규모 외부 정렬 | **최악 상한** 보장 및 $O(1)$ 공간 제한 | 구현 단순성 및 교육 목적 소규모 데이터 |
| 핵심 특징 | **피벗** 분할 및 제자리 교환 | 순차적 분할 및 안정적 **병합** | **최대 힙** 구성 및 루트 반복 추출 | 인접 원소 간 단순 **역순 교환** |
| 한계 | 피벗 불균형 시 최악 $O(n^2)$ 성능 저하 | 입력 크기에 비례하는 $O(n)$ **보조 공간** | 불안정 정렬 및 불리한 **캐시 지역성** | 평균 및 최악 모두 $O(n^2)$ 성능 비효율 |

#### 한줄 요약

- 평균 속도는 퀵, 안정성은 병합, 최악 상한은 힙을 택하고 버블은 교육용으로 제한한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **불균형 분할(Unbalanced Partition)**: 피벗 편향으로 인해 퀵 정렬의 재귀 깊이가 $O(n)$으로 심화되는 현상.
- **무작위 피벗(Random Pivot)**: 최악 분할 패턴 발생을 방지하기 위해 임의의 원소를 피벗으로 추출하는 기법.
- **인트로소트(Introsort)**: 퀵 정렬로 시작하여 재귀 깊이가 깊어지면 힙 정렬로 자동 전환해 최악 $O(n\log n)$을 보장하는 하이브리드 알고리즘.
- **키 사전 계산(Key Precomputation)**: 반복적인 키 평가 연산 부하를 차단하기 위해 정렬 키를 미리 계산 및 저장하는 기법.
- **외부 병합(External Merge)**: 디스크에 분할 정렬되어 저장된 파일 블록(Run)들을 스트리밍 순차 병합하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 가용 메모리 초과로 인메모리 정렬 불가 | 청크 단위 분할 정렬 후 **외부 병합** 적용 | 제한된 메모리에서 전체 데이터 정렬 |
| 다중 키 정렬에서 같은 키의 순서 변동 | **안정 정렬** 선택 | 같은 키의 기존 상대 순서 보존 |
| 피벗 불균형 분할로 인한 **최악 시간복잡도($O(n^2)$)** 발생 | **무작위 피벗** 및 힙 정렬 전환(IntroSort) | 최악 시간복잡도 상한 보장 |
| 복합 키 평가에 따른 높은 비교 연산 비용 발생 | **키 사전 계산** 및 참조 정렬 | 반복 비교 연산 오버헤드 감소 |

#### 한줄 요약

- 메모리 초과 시 외부 병합으로 전환하고, 퀵 정렬의 최악 분할은 IntroSort 하이브리드로 통제하며, 비교 비용이 높으면 키를 미리 계산한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **하이브리드 정렬(Hybrid Sort)**: Timsort(병합+삽입)나 Introsort(퀵+힙+삽입)처럼 상황별 최적 알고리즘을 결합한 표준 라이브러리 정렬 체계.

</details>

- 범용 구현은 **하이브리드 정렬**, 안정성은 병합, 최악 상한은 힙을 선택하고 버블은 교육용으로 제한

#### 한줄 요약

- 평균 속도가 우선이면 퀵 정렬, 동등 키 순서 보존이 필수면 병합 정렬, 최악 시간과 메모리 동시 제한이면 힙 정렬을 선택한다.
