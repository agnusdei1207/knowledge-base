## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **연결 리스트(Linked List)**: 비연속 메모리 공간의 노드들을 포인터 링크로 연결하여 논리적 선형 순서를 구성하는 자료구조.
- **링크(Link)**: 다음 또는 이전 노드의 메모리 주소를 가리키는 포인터 참조 필드.
- **연속 공간(Contiguous Space)**: 물리적 메모리 상에서 데이터가 빈틈없이 연속된 주소에 배치되는 구조.

</details>

- 정의/개념: 비연속 노드를 링크로 연결하여 원소의 논리적 순서를 관리하는 선형 **연결 리스트 자료구조**
- 배경/필요성: 배열 기반 연속 메모리에서는 중간 삽입·삭제 시 후속 원소 전체를 이동하는 $O(n)$ 오버헤드가 발생하므로 $O(1)$ 포인터 갱신 구조 필수

#### 한줄 요약

- 비연속 노드를 링크로 잇고 위치를 알면 링크 변경만으로 $O(1)$ 삽입·삭제 수행

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **순차 접근(Sequential Access)**: 헤드부터 링크를 차례로 따라가 목표 노드에 도달하는 $O(n)$ 탐색 방식.
- **상수 시간 갱신(O(1) Update)**: 선행 노드를 알고 있을 때 포인터 재배치만으로 원소를 삽입·삭제하는 작업.
- **비연속 메모리(Non-contiguous Memory)**: 노드들이 물리적으로 인접하지 않은 힙 주소에 분산 적재되는 상태.

</details>

![연결 리스트와 동적 배열의 위치 접근 단계](/study/diagrams/linked-list-access.svg)

> 목표 위치가 멀어질수록 파란 연결 리스트는 링크 추적 단계가 선형 증가하지만 붉은 동적 배열은 한 단계이며, 임의 접근을 가정한 이론값임

- **링크 연결**을 통해 비연속 메모리 상에서 유연한 크기 확장이 가능한 선형 순서 제공
- 목표 위치까지 포인터를 순차적으로 추적하는 **순차 접근($O(n)$)** 특성
- 선행 노드 포인터 확보 시 단순 링크 변경만으로 완료되는 **상수 시간 갱신($O(1)$)** 지원

#### 한줄 요약

- 임의 접근 시 $O(n)$ 순차 탐색이 요구되나 선행 노드 확보 시 $O(1)$ 포인터 갱신 지원

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **헤드(Head)**: 연결 리스트의 첫 번째 노드를 가리키는 시작 참조 포인터.
- **노드(Node)**: 실제 데이터 값과 다음/이전 노드의 메모리 주소를 함께 보관하는 기본 단위.
- **널(Null)**: 연결할 다음 노드가 없음을 나타내는 종료 표식.
- **데이터 필드(Data Field)**: 노드가 관리하는 실질적 값(Payload)을 저장하는 영역.
- **링크 필드(Link Field)**: 후속 또는 이전 노드의 메모리 주소(Pointer)를 보관하는 영역.

</details>

```text
[ 단일 연결 리스트 전체 및 내부 노드 구조 ]
 
 [ 전체 연결 구조 ]
┌──────┐      ┌──────────────┐      ┌──────────────┐
│ Head ├─────►│ Node 1 (Data)├─────►│ Node 2 (Data)├───► NULL
└──────┘      └──────────────┘      └──────────────┘
 
 [ 내부 노드 구조 ]
┌──────────────────────────────┐
│ 노드 (Node Unit)             │
│  ├─ 데이터 필드 (Data Field) │
│  └─ 링크 필드 (Next Pointer) ├─────► 후속 노드 주소
└──────────────────────────────┘
```

선의 의미: 헤드 포인터에서 시작하여 각 노드의 링크 필드가 다음 노드를 순차 연결하고 마지막 노드가 NULL을 가리키는 포인터 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 헤드 | **헤드**에 첫 노드의 시작 메모리 주소 보관 |
| 노드 | **데이터•링크 필드**를 결합한 최소 메모리 단위 |
| 데이터 필드 | **데이터 필드**에 실질적인 데이터 값 저장 |
| 링크 필드 | 다음 노드 메모리 주소 또는 **널(Null)** 저장 |

#### 한줄 요약

- 헤드가 첫 노드를 가리키고 각 노드는 데이터와 다음 노드 링크를 함께 저장

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **순회(Traversal)**: 헤드에서 시작해 링크를 따라 각 노드를 차례로 방문하는 작업.
- **포인터 추적(Pointer Chasing)**: 메모리 주소를 연속적으로 역참조(Dereference)하며 다음 노드로 이동하는 동작.

</details>

```text
순회 요청
   │
   ▼
1. 첫 노드 참조 (Head 포인터 획득)
   │
   ▼
현재 노드 판정
├─ NULL: 순회 완료
└─ Node
   ├─ 현재 데이터 반환
   └─ 2. 다음 참조로 이동 (Next Pointer 추적)
          │
          └─ 현재 노드 판정으로 반복
```

**동작 원리**

1. **첫 노드 참조**: 헤드가 가리키는 노드를 순회의 현재 노드로 설정
2. **다음 참조 이동**: 현재 값을 처리한 뒤 링크 필드가 가리키는 후속 노드로 이동하고 널(Null)을 만날 때까지 반복

#### 한줄 요약

- 헤드 포인터부터 널(Null) 포인터에 도달할 때까지 포인터 추적을 반복하며 순회

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 연결 리스트(Singly Linked List)**: 각 노드가 다음 노드의 링크 1개만 저장하는 구조.
- **이중 연결 리스트(Doubly Linked List)**: 각 노드가 이전 및 다음 노드의 링크 2개를 모두 저장하는 구조.
- **동적 배열(Dynamic Array)**: 연속 공간을 재할당하며 인덱스 기반 $O(1)$ 임의 접근을 지원하는 배열(std::vector).

</details>

| 비교 항목 | 단일 연결 리스트 (Singly Linked) | 이중 연결 리스트 (Doubly Linked) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|:---|
| 적용 기준 | 메모리 절약 중심 및 단방향 순회 시 | 양방향 순회 및 빈번한 임의 삭제 시 | 인덱스 기반 빠른 $O(1)$ 임의 접근 시 |
| 핵심 특징 | 노드당 1개의 **다음 링크** 유지 | 노드당 **이전•다음 링크** 2개 유지 | 물리적 **연속 공간** 배치 및 캐시 적중 |
| 한계 및 위험 | 역방향 순회 불가 및 삭제 시 선행 탐색 | 추가 포인터 메모리 오버헤드 발생 | 중간 원소 삽입/삭제 시 $O(n)$ 이동 발생 |

#### 한줄 요약

- 잦은 노드 삽입/삭제는 연결 리스트, 인덱스 임의 접근과 캐시 효율은 동적 배열 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **선행 노드 참조(Predecessor Pointer)**: 삽입·삭제 대상 바로 앞 노드를 직접 가리켜 위치 탐색 비용을 없애는 참조.
- **노드 풀(Node Pool)**: 노드 메모리를 블록 단위로 미리 일괄 할당하여 잦은 동적 할당 오버헤드를 줄이는 기법.
- **링크 갱신 순서(Order of Pointer Updates)**: 포인터 유실을 방지하기 위해 새 노드의 링크를 먼저 연결한 뒤 이전 링크를 바꾸는 순서.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대상 위치의 **순차 접근**이 삽입•삭제 비용을 지배 | **선행 노드 참조** 또는 별도 **해시 색인** 유지 | 위치 탐색을 제외한 **상수 시간 갱신** 활용 |
| 잘못된 **링크 갱신 순서**로 후속 사슬 단절 | 후속 링크 보존 후 선행 링크 변경 | 후속 노드까지 연결 무결성 보존 |
| 비연속 노드의 낮은 **캐시 지역성**으로 순회 지연 | **노드 풀**과 묶음 할당으로 인접 배치 | 캐시 미스 감소와 캐시 지역성 개선 |
| 동시 링크 갱신의 경쟁으로 유실•중복 연결 | **뮤텍스 잠금** 또는 Lock-Free **원자적 CAS 연산** 적용 | 동시 갱신 시 **구조 무결성** 확보 |

#### 한줄 요약

- **선행 포인터 캐싱·노드 풀 메모리 연속화·포인터 갱신 순서 준수·Lock-Free 동기화**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **중간 갱신(Middle Update)**: 자료구조의 양 끝단이 아닌 중간 임의 위치에서 원소를 추가하거나 제거하는 연산.

</details>

- 선행 노드 포인터를 확보하고 **중간 갱신**이 빈번한 워크로드는 **연결 리스트** 선택

#### 한줄 요약

- 선행 노드를 미리 알 수 있고 중간 삽입·삭제가 잦을 때 연결 리스트 선택
