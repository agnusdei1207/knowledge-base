## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **포인터 링크(Pointer Link)**: 이전 또는 다음 노드의 물리 메모리 주소를 저장하여 노드 간의 순차적 연결 관계를 형성하는 참조 필드.
- **원소 이동 오버헤드(Element Shifting Overhead)**: 배열의 중간에 데이터를 삽입/삭제할 때 후속 원소들을 한 칸씩 밀거나 당기면서 발생하는 $O(n)$ 연산 비용.

</details>

- 정의/개념: 비연속 메모리 노드들을 **포인터 링크**로 연결하여 논리적 순서를 구성하는 선형 자료구조
- 배경/필요성: 연속 메모리 배열 구조에서 빈번한 중간 원소 삽입·삭제 시 발생하는 대규모 **원소 이동 오버헤드**($O(n)$)

#### 한줄 요약

- 순서의 근거를 연속 배치에서 링크로 옮긴 대가로 갱신은 $O(1)$까지 싸지고 임의 접근은 $O(n)$까지 비싸진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **순차 접근(Sequential Access)**: 헤드부터 링크를 차례로 따라가 목표 노드에 도달하는 $O(n)$ 탐색 방식.
- **상수 시간 갱신(O(1) Update)**: 선행 노드를 알고 있을 때 포인터 재배치만으로 원소를 삽입·삭제하는 작업.
- **비연속 메모리(Non-contiguous Memory)**: 노드들이 물리적으로 인접하지 않은 힙 주소에 분산 적재되는 상태.

</details>

![연결 리스트와 동적 배열의 위치 접근 단계](/study/diagrams/linked-list-access.svg)

> 목표 위치가 멀어질수록 파란 연결 리스트는 링크 추적 단계가 선형 증가하지만 붉은 동적 배열은 한 단계이며, 임의 접근을 가정한 이론값임

- **포인터 링크**를 통해 **비연속 메모리** 상에서 유연한 크기 확장이 가능한 선형 순서 제공
- 목표 위치까지 포인터를 순차적으로 추적하는 **순차 접근($O(n)$)** 특성
- 선행 노드 포인터 확보 시 단순 링크 변경만으로 완료되는 **상수 시간 갱신($O(1)$)** 지원

#### 한줄 요약

- 갱신이 $O(1)$이라는 이점은 선행 노드를 이미 쥐고 있을 때만 성립하므로, 위치 탐색까지 포함하면 배열 대비 이득이 사라진다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **헤드(Head)**: 연결 리스트의 첫 번째 노드를 가리키는 시작 참조 포인터.
- **노드(Node)**: 실제 데이터 값과 다음/이전 노드의 메모리 주소를 함께 보관하는 기본 단위.
- **널(Null)**: 연결할 다음 노드가 없음을 나타내는 종료 표식.
- **데이터 필드(Data Field)**: 노드가 관리하는 실질적 값(Payload)을 저장하는 영역.
- **링크 필드(Link Field)**: 후속 또는 이전 노드의 메모리 주소(Pointer)를 보관하는 영역.

</details>

```text
[단일 연결 리스트 아키텍처]
  │
  ├─ [헤드 포인터] (첫 번째 노드 시작 주소 참조)
  │
  └─ [노드 체인]
        ├─ [데이터 필드] (실제 저장 값·페이로드)
        └─ [링크 필드] (다음 노드 주소 포인터·널 종단)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **헤드** | 첫 번째 **노드**의 시작 메모리 주소를 보관하는 포인터 |
| **노드** | **데이터 필드** 및 **링크 필드**를 결합한 최소 메모리 단위 |
| 데이터 필드 | 실질적인 데이터 값(Payload) 저장 |
| 링크 필드 | 다음 노드 메모리 주소 또는 **널(Null)** 저장 |

#### 한줄 요약

- 노드마다 링크 필드를 함께 싣는 메모리 대가를 치르는 대신 원소를 옮기지 않고 순서를 바꾼다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **순회(Traversal)**: 헤드에서 시작해 링크를 따라 각 노드를 차례로 방문하는 작업.
- **포인터 추적(Pointer Chasing)**: 메모리 주소를 연속적으로 역참조(Dereference)하며 다음 노드로 이동하는 동작.

</details>

```text
[연결 리스트 노드 탐색 및 삽입 요청]
                 │
                 ▼
[1. 헤드(Head) 포인터로부터 탐색 시작]
                 │
                 ▼
        <현재 노드 널(NULL) 판정>
                 │
        ┌────────┴────────┐
        │                 │
    [노드 존재]        [NULL 도달]
        │                 │
        │                 ▼
        │        [탐색 실패 또는 리스트 종료]
        ▼
<목표 노드 위치 일치 판정>
        │
  ┌─────┴─────┐
  │           │
[불일치]    [일치]
  │           │
  │           ▼
  │    [2. 신규 노드 메모리 동적 할당]
  │           │
  │           ▼
  │    [3. 신규 노드의 Next를 현재 노드의 Next로 연결]
  │           │
  │           ▼
  │    [4. 현재 노드의 Next를 신규 노드로 재지정]
  │           │
  ▼           ▼
[5. 다음 포인터 역참조 이동]  [삽입 트랜잭션 완료]
```

분기 결과: 목표 위치를 찾을 때까지 링크를 순차적으로 역참조하며 이동하고, 위치 발견 시 선행 노드 링크 재연결을 통해 $O(1)$로 신규 노드가 삽입됨

**동작 원리**:
1. 리스트 시작점인 **헤드** 포인터를 로드하여 첫 번째 노드의 메모리 주소를 참조하고 **순회**를 개시함.
2. 현재 참조 중인 노드가 **널(Null)**인지 검사하여 리스트 끝 도달 여부를 확인한 후 데이터 필드 값을 목표 키와 비교함.
3. 목표 위치에 도달하지 못한 경우 링크 필드에 저장된 후속 노드 주소를 역참조하여 순차 **포인터 추적**을 지속함.
4. 신규 데이터 삽입 시 힙 메모리에서 신규 **노드**를 할당하고, 신규 노드의 링크 필드에 후속 노드의 시작 주소를 대입함.
5. 직전 선행 노드의 링크 필드가 신규 노드를 가리키도록 단일 포인터 대입 연산을 수행하여 원소 이동 없이 논리적 연결을 완성함.

#### 한줄 요약

- 순회가 링크 역참조의 연속이라 노드 수만큼 캐시 미스가 누적되고, 이것이 같은 $O(n)$인 배열 순회와의 실측 격차를 만든다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **단일 연결 리스트(Singly Linked List)**: 각 노드가 다음 노드의 링크 1개만 저장하는 구조.
- **이중 연결 리스트(Doubly Linked List)**: 각 노드가 이전 및 다음 노드의 링크 2개를 모두 저장하는 구조.
- **동적 배열(Dynamic Array)**: 연속 공간을 재할당하며 인덱스 기반 $O(1)$ 임의 접근을 지원하는 배열(std::vector).
- **연속 공간(Contiguous Space)**: 메모리 상에 빈틈없이 붙어 있어 CPU 캐시 라인 적중률을 극대화하는 물리적 배치.

</details>

| 자료구조 | 단일 연결 리스트 (Singly Linked) | 이중 연결 리스트 (Doubly Linked) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|:---|
| 적용 기준 | 메모리 오버헤드 최소화 및 단방향 큐/스택 구현 시 | 양방향 탐색 및 특정 노드 즉시 삭제(LRU 캐시) 요구 시 | 인덱스 기반 $O(1)$ 초고속 임의 접근 및 캐시 활용 시 |
| 핵심 특징 | 노드당 1개의 다음 링크 유지 | 노드당 이전·다음 링크 2개 유지 | 물리적 **연속 공간** 배치 및 캐시 적중 |
| 한계 | 역방향 순회 불가 및 삭제 시 선행 탐색 | 추가 포인터 메모리 오버헤드 발생 | 중간 원소 삽입/삭제 시 $O(n)$ 이동 발생 |

#### 한줄 요약

- 세 구조 모두 순서 유지 비용을 어디서 치를지의 선택이며, 잦은 삽입·삭제는 연결 리스트가, 인덱스 접근과 캐시 효율은 동적 배열이 유리하다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **선행 노드 참조(Predecessor Pointer)**: 삽입·삭제 대상 바로 앞 노드를 직접 가리켜 위치 탐색 비용을 없애는 참조.
- **해시 색인(Hash Index)**: 특정 노드의 위치를 $O(1)$에 찾기 위해 키와 노드 포인터를 매핑해 두는 보조 인덱스.
- **캐시 지역성(Cache Locality)**: 최근 참조한 주소나 인접 주소를 곧 다시 참조하는 성질로, 연속 배치된 데이터가 캐시 라인 단위로 함께 적재되어 CPU 캐시 적중률을 높이는 특성.
- **노드 풀(Node Pool)**: 노드 메모리를 블록 단위로 미리 일괄 할당하여 잦은 동적 할당 오버헤드를 줄이는 기법.
- **링크 갱신 순서(Order of Pointer Updates)**: 포인터 유실을 방지하기 위해 새 노드의 링크를 먼저 연결한 뒤 이전 링크를 바꾸는 순서.
- **뮤텍스(Mutual Exclusion, Mutex)**: 임계 구역에 오직 하나의 스레드만 진입하도록 보장하는 상호 배제 잠금 기법.
- **비교 및 교환(Compare-And-Swap, CAS)**: 메모리 위치의 값이 기대값과 같을 때만 새 값으로 원자적 교체하는 락프리 하드웨어 동기화 연산.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 대상 위치의 **순차 접근** 삽입·삭제 비용을 지배 | **선행 노드 참조** 또는 별도 **해시 색인** 유지 | 위치 탐색 오버헤드 제거를 통한 **상수 시간 갱신** 달성 |
| 잘못된 **링크 갱신 순서**로 인한 후속 사슬 단절 | 후속 링크 보존 후 선행 링크 변경 | 후속 노드까지 연결 무결성 보존 |
| 비연속 노드의 낮은 **캐시 지역성**으로 순회 지연 | **노드 풀** 및 묶음 할당으로 인접 배치 | 캐시 미스 감소와 캐시 지역성 개선 |
| 동시 링크 갱신 경쟁으로 노드 유실 및 순환 참조 발생 | **뮤텍스** 잠금 또는 Lock-Free 원자적 **CAS** 연산 적용 | 동시 갱신 시 구조 무결성 확보 |

#### 한줄 요약

- 단일 연결에서는 선행 포인터를 미리 캐싱해야 삭제가 안전하고, 노드를 풀로 연속 배치하면 캐시 지역성이 개선되며, 멀티스레드 환경에서는 원자적 CAS로 링크 갱신 순서를 보장해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **최근 최소 사용(Least Recently Used, LRU)**: 캐시 공간 부족 시 가장 오랫동안 참조되지 않은 항목을 우선 교체하는 대표적 페이지/캐시 교체 알고리즘.
- **언롤드 연결 리스트(Unrolled Linked List)**: 하나의 노드 내부에 고정 크기의 소형 배열을 두어 포인터 역참조 오버헤드를 줄이고 캐시 지역성을 높인 변형 리스트.
- **무잠금(Lock-Free)**: 상호 배제 잠금(Mutex)을 배제하고 하드웨어 원자적 연산을 사용하여 다중 스레드 간 경합 지연을 최소화하는 동시성 제어 기법.

</details>

- 연결 리스트는 **LRU** 캐시 및 커널 큐의 기반으로 안착되었으며, 현대 고성능 엔진에서는 캐시 미스를 억제하는 **언롤드 연결 리스트(Unrolled Linked List)** 및 **무잠금(Lock-Free)** 원자적 자료구조로 진화 추세.
- $O(1)$ 삽입·삭제 이점과 포인터 역참조에 따른 CPU 캐시 미스 오버헤드를 동적 배열의 메모리 연속성과 비교 평가한 공학적 절충 필요.

#### 한줄 요약

- 무잠금 동기화와 언롤드 구조로 진화하는 연결 리스트 특성을 고려하여 캐시 지역성과 갱신 빈도 간 최적의 자료구조 절충 필요.
