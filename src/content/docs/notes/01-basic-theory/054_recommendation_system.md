## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **추천 시스템(Recommendation System)**: 사용자의 과거 행동 이력(클릭, 구매, 평점)과 아이템의 메타데이터 속성을 분석하여 개인화된 선호 아이템 목록을 순위화(Ranking)하여 제공하는 지능형 서비스.
- **협업 필터링(CF, Collaborative Filtering)**: "유사한 행동을 보인 사용자들은 미래에도 유사한 선호를 보일 것"이라는 가정 하에 사용자-아이템 상호작용 행렬 패턴만을 활용하는 추천 기법.
- **콘텐츠 기반 필터링(CBF, Content-Based Filtering)**: 아이템의 텍스트, 장르, 태그 등 고유 속성과 사용자의 프로필 벡터 간의 코사인 유사도를 기반으로 추천하는 기법.
- **콜드 스타트(Cold Start)**: 신규 사용자(User)나 신규 아이템(Item)에 대한 과거 상호작용 이력이 전무하여 신뢰성 있는 추천을 생성할 수 없는 고질적 결함 상태.

</details>

- 정의/개념: 대규모 아이템 풀에서 사용자의 잠재적 선호도를 예측하여 **2단계 파이프라인(후보군 생성 $\to$ 랭킹/재정렬)을 거쳐 개인화된 추천 목록을 서빙하는 AI 아키텍처**
- 배경/필요성: 수억 개의 상품이 존재하는 이커머스/OTT 환경에서 정보 과부하(Information Overload)를 해소하고 **사용자 체류 시간, 구매 전환율(CVR) 및 매출 극대화 필수**

#### 한줄 요약

- 행동 이력 기반 협업 필터링과 속성 기반 콘텐츠 필터링을 결합하여 개인화 순위를 결정

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **행렬 분해(MF, Matrix Factorization)**: 거대한 사용자-아이템 평점 행렬 $R_{M \times N}$을 저차원 잠재 요인 행렬 $P_{M \times k}$와 $Q_{N \times k}$의 곱($R \approx P Q^T$)으로 분해하여 결측값을 예측하는 SVD 기반 기법.
- **암묵적 피드백(Implicit Feedback)**: 명시적 평점(1~5점) 대신 클릭, 조회, 스크롤, 체류 시간 등 사용자의 간접적 상호작용 로그로부터 선호도를 추정하는 신호.

</details>

- 사용자-아이템 상호작용 행렬의 극단적 희소성($99.9\%$ 이상 빈칸) 극복을 위한 **잠재 요인(Latent Factor) 임베딩**
- 신규 진입 시의 **콜드 스타트(Cold Start) 및 인기 아이템에 쏠리는 롱테일(Long-Tail) 편향 존재**
- 대규모 실시간 서빙을 위한 **2-Stage(후보 생성 Retrieval $\to$ 랭킹 Ranking) 계층 분리**

#### 한줄 요약

- 상호작용 행렬의 희소성을 잠재 임베딩으로 극복하고, 2단계 파이프라인으로 실시간 서빙

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **추천 시스템 2-Stage 서빙 아키텍처**:
  - Retrieval (후보 생성): 수백만 개 아이템 $\to$ 수백 개 후보군으로 축소 (ANN 초고속 검색).
  - Ranking (정밀 랭킹): 수백 개 후보군 $\to$ 딥러닝 랭커(DLRM, DIN)로 정밀 점수화 및 Top-K 정렬.

</details>

```text
[ 현대 추천 시스템 표준 2-Stage 서빙 아키텍처 ]
 전체 아이템 풀 (수백만 개)
         │
         ▼
 ┌───────────────────────────────────────────────────────────┐
 │ 1단계: 후보 추출기 (Retrieval Stage)                      │ ── Two-Tower / ANN 벡터 서치
 │ (사용자 임베딩 u와 아이템 임베딩 v의 유사도로 Top-200 축소)│
 └─────────────────────────────┬─────────────────────────────┘
                               │ (수백 개 후보군)
                               ▼
 ┌───────────────────────────────────────────────────────────┐
 │ 2단계: 정밀 랭킹 모델 (Ranking Stage: DLRM, DeepFM)       │ ── CTR / CVR 정밀 확률 점수화
 └─────────────────────────────┬─────────────────────────────┘
                               │
                               ▼
 ┌───────────────────────────────────────────────────────────┐
 │ 3단계: 재정렬 및 필터링 (Re-ranking: 다양성, 중복제거)    │ ── 품절 제외 및 비즈니스 룰
 └─────────────────────────────┬─────────────────────────────┘
                               │
                               ▼
           최종 사용자 개인화 추천 목록 (Top-10)
```

선의 의미: 전체 아이템 풀에서 후보군 추출, 딥러닝 정밀 랭킹, 비즈니스 룰 재정렬 및 최종 서빙 파이프라인.

| 구성요소 | 책임 |
|:---|:---|
| 후보 추출기 (Retrieval) | Two-Tower 임베딩 및 **ANN 검색으로 밀리초 내 수백 개 후보 압축** |
| 랭킹 엔진 (Ranker) | 유저/아이템/문맥 피처 결합으로 **정밀 클릭률($\hat{p}_{CTR}$) 추정** |
| 재정렬기 (Re-ranker) | 카테고리 다양성 보장, 기구매 제외, **비즈니스 가중치 반영** |
| 피드백 수집 파이프라인 | 노출/클릭 로그를 Kafka로 스트리밍하여 **실시간 피처 갱신 및 재학습** |

#### 한줄 요약

- Two-Tower 모델로 후보군을 고속 추출하고, 딥러닝 랭커로 정밀 순위를 매겨 서빙

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **Two-Tower 아키텍처**: 유저 타워($f_{user}(X_u)$)와 아이템 타워($g_{item}(X_i)$)를 독립 신경망으로 구성하여 아이템 임베딩을 사전 벡터 DB(Milvus/Faiss)에 인덱싱해 두고 유저 쿼리 시 내적($u \cdot v$)으로 즉시 검색하는 구조.

</details>

```text
유저 추천 요청 인입 (User ID + Context)
   │
   ▼
[ 1. 실시간 유저 임베딩 벡터 u 생성 (User Tower 통과) ]
   │
   ▼
[ 2. 벡터 DB(Faiss / Milvus)에서 ANN 코사인 유사도 기반 Top-200 후보 추출 ]
   │
   ▼
[ 3. 후보군 200개에 대해 정밀 피처(유저 행동, 아이템 메타, 문맥) 조인 ]
   │
   ▼
[ 4. 랭킹 모델(DeepFM / DLRM) 통과: 클릭 확률 p_CTR 산출 및 정렬 ]
   │
   ▼
[ 5. 비즈니스 룰 적용 (다양성 증대, 품절 필터링) 후 최종 Top-10 반환 ]
   │
   ▼
[ 6. 사용자 노출 및 클릭/미클릭 로그를 데이터 레이크로 비동기 수집 ]
```

**동작 원리**

1. **유저 임베딩 추출**: 접속한 유저의 최근 클릭 이력을 임베딩 벡터로 변환
2. **ANN 초고속 매칭**: 사전 인덱싱된 수백만 개 아이템 중 코사인 거리가 가까운 200개 선별
3. **피처 엔지니어링**: 유저-아이템 상호작용 피처(교차 특성)를 결합
4. **정밀 랭킹**: 딥러닝 모델로 각 후보 아이템의 구매 전환 확률 계산
5. **서빙 및 피드백**: 최종 목록을 렌더링하고 유저 반응 로그를 수집하여 모델에 환류

#### 한줄 요약

- Two-Tower로 후보군을 추출하고 랭킹 모델로 정렬한 뒤 사용자 반응을 로그로 환류

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **추천 시스템 3대 기법 비교**:
  - 협업 필터링 (CF): 유저-아이템 행렬 기반, 도메인 지식 불필요, 콜드 스타트 취약.
  - 콘텐츠 기반 (CBF): 텍스트/장르 속성 기반, 콜드 스타트 강건, 유사 아이템만 추천(고립).
  - 하이브리드 추천: CF + CBF 결합, 딥러닝 기반 2-Stage, 산업 현장 표준.

</details>

| 비교 항목 | 협업 필터링 (CF) | 콘텐츠 기반 (CBF) | 하이브리드 추천 (Hybrid) |
|:---|:---|:---|:---|
| 핵심 데이터원 | **사용자-아이템 상호작용 로그** | **아이템 속성 텍스트/장르 메타** | **상호작용 로그 + 아이템/유저 속성** |
| 신규 유저/아이템 | **콜드 스타트 시 완전 불능** | **신규 아이템도 즉시 추천 가능** | **속성 기반으로 콜드 스타트 극복** |
| 추천의 의외성 | **우수한 세렌디피티(Serendipity)** | 기존 선호 속성에 고립(Filter Bubble) | **정밀도와 의외성의 조화** |
| 알고리즘 예시 | Matrix Factorization, Item2Vec | TF-IDF, BERT 임베딩 코사인 유사도 | **Two-Tower, DeepFM, DLRM** |

#### 한줄 요약

- 이력 풍부는 협업 필터링, 신규 대상은 콘텐츠 기반, 상용 서비스는 하이브리드 추천을 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **노출 편향(Position/Exposure Bias)**: 화면 상단에 노출된 아이템이 단순히 위치 때문에 더 많이 클릭되는 현상으로, Inverse Propensity Scoring(IPS)을 통해 클릭 가중치를 보정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신규 유저/아이템의 **극심한 콜드 스타트(Cold Start)** | **온보딩 관심사 조사 + 콘텐츠 속성 기반 탐색 노출** | 초기 상호작용 로그 신속 확보 |
| 인기 아이템만 반복 추천되는 **인기 편향 및 필터 버블** | **IPS(Inverse Propensity Scoring) 및 $\epsilon$-Greedy 탐색** | 롱테일(Long-tail) 아이템 발굴 |
| 수백만 개 아이템 실시간 추천 시 **서빙 지연(SLA 위반)** | **Two-Tower + Faiss / HNSW ANN 인덱싱 파이프라인** | 밀리초(ms) 단위 초저지연 응답 |
| 사용자의 순간적 의도(Intent) 미반영 | **세션 기반 추천(Session-based Transformer/SASRec)** | 현재 세션 문맥 실시간 반영 |

#### 한줄 요약

- 콜드 스타트는 온보딩 속성 추천으로 극복하고, 인기 편향은 IPS로 보정하며, 대규모 임베딩 검색은 Faiss HNSW로 가속하고, 세션 추천에는 SASRec를 적용한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **상용 추천 엔지니어링 표준**: 글로벌 빅테크(YouTube, Netflix, 쿠팡)는 대규모 Two-Tower 기반 Retrieval과 다중 모달 딥러닝 Ranker(DLRM), 실시간 세션 그래프 모델을 결합한 엔드투엔드 하이브리드 파이프라인을 운영.

</details>

- 상호작용 풍부 시 **행렬분해(MF)/DeepCF**, 신규 유저/아이템은 **콘텐츠 기반**, 대규모 상용 서비스는 하이브리드 2-Stage(후보추출+랭킹) 선택

#### 한줄 요약

- 이력이 충분하면 협업 필터링, 신규 대상은 콘텐츠 기반, 대규모 상용 서비스는 하이브리드를 선택
