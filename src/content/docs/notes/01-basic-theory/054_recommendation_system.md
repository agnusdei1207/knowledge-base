## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **추천 시스템**: 사용자 선호도를 예측해 아이템의 노출 순서를 개인화하는 시스템이다.
- **개인화**: 사용자별 행동과 속성에 따라 서로 다른 결과를 제공하는 방식이다.
- **선호도**: 사용자가 특정 아이템을 클릭•구매•평가할 가능성이나 기호의 정도이다.
- **노출 순위**: 사용자 화면에 아이템을 보여 주는 순서이다.

</details>

- 정의/개념: **추천 시스템**은 사용자 행동과 아이템 속성 및 현재 문맥으로 **선호도**를 예측해 후보를 생성하고 **개인화**된 노출 순위를 정하는 시스템이다.
- 배경/필요성: 아이템 수가 많고 관측된 사용자 반응이 희소하면 전체 목록에서 관련 항목을 직접 찾기 어렵고 미노출을 비선호로 오해할 수 있다.

#### 한줄 요약

- 추천 시스템은 사용자의 과거 행동과 아이템 속성을 기반으로 개인화된 노출 순위를 결정하는 모델이다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **상호작용 행렬**: 사용자별 아이템 클릭•구매 같은 반응을 기록한 희소 행렬이다.
- **암묵 피드백**: 클릭•구매•체류 시간에서 간접적으로 추정한 선호 신호이다.
- **노출 편향**: 노출된 아이템에만 반응 로그가 생겨 관측 데이터가 전체 선호를 대표하지 못하는 현상이다.
- **미관측 피드백**: 사용자에게 노출되지 않았거나 반응이 기록되지 않아 선호 여부를 알 수 없는 항목이다.
- **다목적 최적화**: 정확도•다양성•신선도처럼 여러 목표를 동시에 균형 있게 개선하는 과정이다.

</details>

- 희소한 **상호작용 행렬**의 클릭•구매 암묵 피드백 활용이 핵심이다.
- **미관측 피드백•노출 편향**에 따른 학습 데이터 왜곡이 핵심이다.
- 정확도•다양성•신선도 간 **다목적 최적화**가 핵심이다.

#### 한줄 요약

- 사용자•상품 격자의 빈칸은 비선호가 아니라 미노출일 수 있으므로, 모두 부정 반응으로 처리하면 인기 상품 쏠림이 커진다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **후보 생성**: 전체 아이템 중 정밀 평가할 소수 후보군을 빠르게 추리는 단계이다.
- **랭킹**: 후보별 선호 점수를 계산해 최종 노출 순서를 정하는 단계이다.
- **피드백 파이프라인**: 노출과 사용자 반응을 수집해 다음 학습 데이터로 되돌리는 처리 경로이다.
- **상호작용 이력**: 사용자와 아이템 사이의 클릭•구매•평가를 기록한 데이터이다.
- **선호 점수**: 랭킹 모델이 사용자별 아이템 적합도를 수치화한 값이다.
- **재학습 데이터**: 노출과 반응 로그를 정제해 다음 모델 학습에 사용하는 데이터이다.
- **추천 후보**: 전체 아이템 중 랭킹 모델이 정밀 평가하도록 후보 생성기가 추린 항목 집합이다.

</details>

```text
[데이터 저장소] -- [후보 생성기] -- [랭킹 모델]
       |                                  |
       +------ [피드백 파이프라인] -------+
```

선의 의미: 후보 생성기와 랭킹 모델이 저장 데이터와 추천 후보를 공유하고, 피드백 파이프라인이 랭킹 결과와 데이터 저장소에 함께 접하는 정적 네트워크 관계다.

| 구성요소 | 책임 |
|:---|:---|
| 데이터 저장소 | 사용자•아이템 특징과 **상호작용 이력** 보관 |
| 후보 생성기 | 전체 아이템에서 **추천 후보**를 빠르게 축소 |
| 랭킹 모델 | 후보별 **선호 점수•노출 순위** 산출 |
| 피드백 파이프라인 | 노출•반응 로그를 **재학습 데이터**로 전환 |

#### 한줄 요약
- 후보 생성 모델에서 후보 아이템을 추출하여 랭킹 모델로 순위를 산출하고, 사용자 피드백 로그를 재학습 데이터로 반환하는 구조이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **사용자 특징(User Feature)**: 사용자의 프로필과 속성을 나타내는 정보이다.
- **아이템 특징(Item Feature)**: 아이템의 내용과 범주를 나타내는 정보이다.
- **노출 로그**: 어떤 아이템이 어떤 사용자에게 언제 표시됐는지 기록한 데이터이다.
- **특징•이력 조회**: 사용자•아이템 특징과 상호작용 이력을 저장소에서 읽는 단계이다.
- **추천 후보 생성**: 전체 아이템에서 랭킹할 소수 후보군을 빠르게 추리는 단계이다.
- **선호 점수•순위 산출**: 후보별 적합도를 계산해 최종 노출 순서를 정하는 단계이다.
- **노출•반응 로그 정제**: 노출 기록과 클릭•구매 반응을 결합하고 오류를 제거해 학습 데이터로 만드는 단계이다.

</details>

```text
[사용자 추천 요청]
        |
        v
+----------------------------------+
| 추천 서비스                      |
|                                  |
|  1. 특징•이력 조회               |
|            |                     |
|            v                     |
|  2. 추천 후보 생성               |
|            |                     |
|            v                     |
|  3. 선호 점수•순위 산출          |
+----------------------------------+
        |
        v
[추천 노출과 사용자 반응]
        |
        v
+----------------------------------+
| 데이터•피드백 플랫폼             |
|                                  |
|  4. 노출•반응 로그 정제          |
+----------------------------------+
        |
        `----> 다음 학습•추천 데이터로
```

### 동작 원리

- **1. 특징•이력 조회**: **사용자 특징**•**아이템 특징**•상호작용을 확인한다.
- **2. 추천 후보 생성**: 전체 아이템에서 평가 후보군을 축소한다.
- **3. 선호 점수•순위 산출**: 후보별 적합도와 노출 순서를 결정한다.
- **4. 노출•반응 로그 정제**: **노출 로그**와 반응을 결합해 다음 학습용 피드백 데이터를 생성한다.

#### 한줄 요약

- 전체 아이템 풀에서 후보군을 추출하여 노출 순위를 산출하고, 클릭 로그를 다음 학습 데이터로 환류하는 과정이다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **협업 필터링**: 사용자와 아이템의 상호작용 패턴을 활용하는 추천 방식이다.
- **콘텐츠 기반 추천**: 사용자 선호와 아이템 속성의 유사성을 활용하는 추천 방식이다.
- **하이브리드 추천**: 상호작용 정보와 아이템 속성을 결합하는 방식이다.
- **콜드 스타트(Cold Start)**: 신규 사용자나 아이템에 이력이 없어 추천 근거가 부족한 상태이다.
- **운영 비용**: 여러 추천 모델과 데이터를 실행•관리하는 데 드는 자원과 복잡도이다.
- **혼재 구간**: 이력이 충분한 사용자•아이템과 신규 대상이 함께 존재하는 상태이다.

</details>

| 추천 방식 | 협업 필터링 | 콘텐츠 기반 | 하이브리드 추천 |
|:---|:---|:---|:---|
| 적용 기준 | **상호작용 이력**이 충분히 축적된 경우 | 신규 아이템처럼 **콜드 스타트** 상태인 경우 | 이력이 부족한 구간과 충분한 구간이 섞인 **혼재 구간** |
| 핵심 특징 | 사용자•아이템 행동 패턴 활용 | 프로필•아이템 속성 유사도 활용 | 행동 이력과 속성 예측 결합 |
| 한계 | 신규 사용자•아이템 **콜드 스타트** | 유사 속성 추천 편중 | 구조 복잡도•**운영 비용** 증가 |

> 요약: 이력 부족은 **콘텐츠 기반 추천**, 축적 후에는 **협업 필터링**이 핵심이다.

#### 한줄 요약

- 상호작용 이력은 협업 필터링, 아이템 속성 벡터는 콘텐츠 기반 추천, 혼재 구간은 두 방식을 결합한 하이브리드 추천으로 처리하는 과정이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **탐색 노출**: 이력이 부족한 아이템을 일부 노출해 초기 선호 신호를 모으는 방법이다.
- **인기 편향**: 인기 아이템이 반복 노출되어 상호작용이 다시 인기 항목에 쏠리는 현상이다.
- **근사 최근접 이웃 탐색(Approximate Nearest Neighbor Search, ANN Search)**: 모든 아이템을 비교하지 않고 가까운 후보를 빠르게 찾는 기법이다.
- **노출 확률 보정**: 아이템이 보여질 기회가 달랐음을 반영해 학습 가중치를 조정하는 처리이다.
- **롱테일(Long Tail)**: 인기는 낮지만 종류가 매우 많은 아이템 집합이다.
- **부정 표본**: 사용자가 선호하지 않는다고 간주해 학습에 사용하는 아이템 사례이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 신규 사용자•아이템의 추천 공백 | 속성 기반 **하이브리드 추천**•**탐색 노출** | **콜드 스타트** 완화 |
| **인기 편향**으로 노출 집중 | 다양성 제약•**노출 확률 보정** | **롱테일** 노출 기회 확대 |
| **미관측 피드백**을 비선호로 오인 | **노출 로그** 분리•**부정 표본** 재정의 | 선호 학습 왜곡 감소 |
| 후보 생성 응답 지연 | 사전 색인•**근사 최근접 이웃 탐색** 적용 | 목표 지연 내 후보 규모 유지 |

#### 한줄 요약

- 신규 아이템을 콘텐츠 기반 추천으로 탐색 노출하여 초기 클릭 로그를 수집한 뒤 협업 필터링으로 전환하는 과정이다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **이력 밀도**: 가능한 사용자•아이템 조합 중 상호작용이 기록된 비율이다.
- **추천 방식 선택 기준**: 상호작용 이력의 밀도와 신규 대상의 혼재 여부로 추천 방식을 고르는 기준이다.

</details>

- **추천 방식 선택 기준**에 따라 **이력 밀도**가 높으면 **협업 필터링**, 신규 대상은 **콘텐츠 기반 추천**, **혼재 구간**은 **하이브리드 추천**을 선택한다.

#### 한줄 요약

- 상호작용 이력이 충분하면 협업 필터링, 신규 아이템이면 콘텐츠 기반 추천, 혼재 구간이면 하이브리드 추천을 선택하는 과정 원칙 준수
