## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **백트래킹(Backtracking)**: 제약을 어긴 분기를 버리고 이전 선택으로 돌아가 다른 후보를 탐색하는 기법
- **조합 폭발(Combinatorial Explosion)**: 후보 조합이 지수적으로 늘어 실행 가능한 시간이나 메모리를 초과하는 현상
- **제약 위반**: 현재 선택이 문제에서 요구한 조건을 만족하지 못하는 상태

</details>

- 정의/개념: **제약 위반** 분기를 제거하고 이전 선택으로 복귀하는 탐색 기법
- 배경/필요성: 제약 충족 문제의 **조합 폭발** 억제

#### 한줄 요약

- 스도쿠에서 규칙을 어긴 값을 지우고 이전 선택으로 돌아가 다른 후보를 시험하는 방식이다.


## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **상태 공간 트리(State Space Tree)**: 부분해를 노드로 펼쳐 가능한 선택 경로를 표현한 탐색 공간
- **유망성(Promising)**: 현재 부분해가 유효한 완성 해로 확장될 수 있는 성질
- **가지치기(Pruning)**: 해로 확장될 수 없는 분기를 제거해 탐색량을 줄이는 동작
- **역순 복구**: 최근 선택으로 바뀐 상태부터 거꾸로 되돌려 다음 후보의 독립성을 지키는 작업
- **깊이 우선 탐색(Depth-First Search, DFS)**: 한 선택 경로를 끝까지 확장한 뒤 이전 분기로 돌아오는 탐색 방식

</details>

- **상태 공간 트리** 를 **깊이 우선** 으로 순회•상태 복원
- **유망성** 판정으로 위반 분기 **가지치기**해 탐색량 축소
- 선택 전 상태를 보존하는 **역순 복구** 로 후보 독립성 유지

#### 한줄 요약

- 스도쿠의 모순을 일찍 찾을수록 그 아래 후보를 한꺼번에 버릴 수 있다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **재귀 탐색(Recursive Search)**: 유망한 부분해를 다음 단계 입력으로 삼아 같은 탐색 함수를 다시 호출하는 동작
- **부분해(Partial Solution)**: 일부 변수만 정해져 아직 완성되지 않은 해
- **복구 상태(Restoration State)**: 후보 선택으로 바뀐 값과 순서를 기록해 선택 전 상태로 되돌리는 정보
- **유망성 판정 함수**: 부분해가 유효한 해로 자랄 수 있는지 제약으로 검사하는 함수

</details>

```text
[재귀 탐색 함수]
    |
    +-- [후보 생성기]
    +-- [부분해 저장소]
    `-- [유망성 판정 함수]
```

선의 의미: 재귀 탐색 함수가 후보 열거, 부분해와 복구 상태 보관, 유망성 검사를 각각 이용하는 정적 의존 관계

| 구성요소 | 책임 |
|:---|:---|
| 재귀 탐색 함수 | **깊이 우선**으로 부분해 확장•복귀 |
| 후보 생성기 | 현재 단계의 **선택 후보** 열거 |
| 부분해 저장소 | 선택 변수값과 **복구 상태** 보관 |
| 유망성 판정 함수 | **제약 위반**으로 분기 확장 판정 |

#### 한줄 요약

- 재귀 탐색 함수가 후보를 부분해에 적용하고, 제약을 위반하면 저장한 변경 내역으로 선택 전 상태를 복구한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **제약 충족 문제(Constraint Satisfaction Problem, CSP)**: 여러 제약을 모두 만족하는 변수값 조합을 찾는 문제
- **후보 생성기**: 현재 선택 단계에서 시도할 수 있는 변수값을 열거하는 구성요소
- **상태 복구**: 재귀 탐색에서 돌아온 뒤 선택으로 바뀐 부분해를 이전 상태로 환원하는 작업

</details>

```text
[탐색 요청]
     |
+---- 후보 존재•해 미완성 동안 반복 ----+
|    [1. 다음 후보 선택]                 |
|              |                         |
|    [2. 후보값•복구 정보 저장]          |
|              |                         |
|    [3. 유망성 판정]                    |
|       +---- 완성 ----> [완성 해 반환]  |
|       |                                |
|       +---- 유망•미완성                |
|       |          |                     |
|       | [4. 하위 단계 재귀 탐색]       |
|       |          |                     |
|       `---- 위반•재귀 복귀             |
|                  |                     |
|          [5. 상태 복구]                |
|                  |                     |
|                  `---------- 반복 ------+
+----------------------------------------+
     |
[실패 반환]
```

**동작 원리**

1. **다음 후보 선택**: 현재 단계의 선택값 획득
2. **후보값•복구 정보 저장**: 선택과 변경 내역을 부분해에 적용
3. **유망성 판정**: 가지치기•재귀 확장•완성 여부 결정
4. **하위 단계 재귀 탐색**: 유망한 부분해에서 다음 후보 탐색
5. **상태 복구**: 재귀 복귀 후 선택 전 상태로 환원

#### 한줄 요약

- 스도쿠 숫자를 연필로 써 제약을 확인하고, 모순이면 지우개로 이전 상태를 복구한 뒤 다음 숫자를 시험한다.


## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **완전 탐색(Exhaustive Search)**: 가능한 후보를 모두 생성하고 검사해 해를 찾는 방식
- **분기 한정(Branch and Bound)**: 목적 함수의 경계로 최적값을 개선할 수 없는 분기를 제거하는 방식
- **목적 함수(Objective Function)**: 완성 해의 비용이나 이익을 수치화하는 함수
- **경계(Bound)**: 현재 부분해의 하위 분기에서 얻을 수 있는 최선의 목적값 한계
- **지수 시간(Exponential Time)**: 입력 증가에 따라 실행 단계가 지수적으로 늘어나는 시간복잡도

</details>

| 탐색 전략 | 백트래킹 | 완전 탐색 | 분기 한정 |
|:---|:---|:---|:---|
| 적용 기준 | 부분해 단계에서 위반 **조기 판정** 가능 | 모든 후보의 **계산 시간** 감당 가능 | **목적 함수** 경계 산출 가능 |
| 핵심 특징 | **제약 위반** 분기 제거 | 모든 후보 **전수 검사** | **상•하한** 비교로 분기 폐기 |
| 한계 | 제약 판정 지연 시 **지수 시간** 잔존 | 후보 **조합 폭발** | **경계 계산** 오버헤드 |

> 요약: 제약 위반은 백트래킹, 목적값 개선 불가는 **분기 한정**

#### 한줄 요약

- 스도쿠처럼 규칙 위반을 중간에 알면 백트래킹, 남은 선택으로도 최고 점수를 못 넘는다고 알면 분기 한정으로 가지를 자른다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **강한 제약**: 낮은 검사 비용으로 많은 무효 후보를 조기에 제거할 수 있는 조건
- **상태 독립성**: 한 분기에서 바꾼 값이 복구되어 다른 후보의 탐색 결과에 영향을 주지 않는 성질
- **명시적 스택**: 재귀 호출 대신 프로그램이 직접 부분해와 복귀 상태를 넣고 꺼내는 저장 구조
- **탐색 공간**: 후보 선택으로 만들 수 있는 모든 부분해와 완성 해의 집합
- **깊이 한도**: 재귀나 탐색이 진행할 수 있는 최대 단계를 제한한 기준

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 늦은 **가지치기** 로 무효 부분해의 하위 조합까지 탐색 | 비용이 낮고 강한 제약부터 검사 | 불필요한 **탐색 노드 수 감소** |
| 부분해 복구 누락으로 이전 후보의 변경이 다음 후보에 잔존 | 변경 항목 기록 후 역순 복구 | 분기별 **상태 독립성** 확보 |
| 비효율적 후보 순서로 같은 해의 탐색 노드 급증 | 제약이 많은 변수•값부터 선택 | 해 발견 전 **탐색 공간 축소** |
| 큰 상태 공간의 깊은 재귀로 호출 스택 초과 | 깊이 한도 또는 명시적 스택 적용 | 깊은 탐색의 **호출 스택 초과 방지** |

#### 한줄 요약

- 실패한 선택의 변경을 역순으로 되돌려 다음 후보에 흔적을 남기지 않는다.


## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **조기 판정**: 부분해가 완성되기 전에 제약 위반 여부를 확인해 하위 분기를 제거하는 판단

</details>

- 부분해의 **제약 위반** 을 조기에 판정하면 백트래킹 선택

#### 한줄 요약

- 완성 전에 틀린 선택을 알아낼 수 있는 문제일수록, 그 아래 후보를 통째로 지우는 백트래킹의 이득이 커진다.
