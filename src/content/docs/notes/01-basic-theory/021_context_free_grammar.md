## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **문맥 자유 문법(Context-Free Grammar, CFG)**: 좌변이 단일 비단말 기호로만 구성되어 주변 문맥과 무관하게 생성 규칙($A \to \alpha$)을 적용하는 촘스키 2형식 문법.
- **비단말 기호(Non-terminal Symbol, $V$ 또는 $N$)**: 다른 기호열로 추가 치환 가능한 구문 범주.
- **단말 기호(Terminal Symbol, $\Sigma$ 또는 $T$)**: 더 이상 치환되지 않고 소스 코드에 직접 나타나는 어휘 토큰.
- **재귀 구문(Recursive Syntax)**: 괄호의 짝 맞춤, 수식의 연산자 중첩, 블록 제어문처럼 자기 자신을 재귀적으로 포함하는 계층적 구문 구조.

</details>

- 정의/개념: 단일 비단말을 문자열로 치환하는 생성 규칙을 재귀적으로 적용하여 임의 깊이의 중첩 구조를 표현하는 **문맥 자유 문법(CFG)**
- 배경/필요성: 정규 문법(Type-3)의 유한 상태 메모리 제약으로 인한 임의 깊이의 괄호 짝 맞춤 및 재귀적 중첩 블록 구조 표현의 한계

#### 한줄 요약

- 좌변을 단일 비단말로 묶어 문맥 검사 능력을 포기한 대가로 중첩 깊이를 무제한으로 얻으므로, 선언-사용 일치 같은 문맥 제약은 문법 밖 의미 분석으로 미뤄진다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **유도(Derivation)**: 시작 기호 $S$로부터 생성 규칙들을 반복 적용하여 최종 단말 문자열을 생성해 나가는 수학적 치환 과정.
- **모호성(Ambiguity)**: 하나의 단말 문자열에 대해 서로 다른 2개 이상의 유효한 구문 트리 또는 최좌단 유도가 존재하는 문법적 불완전성.
- **푸시다운 오토마타(Pushdown Automaton, PDA)**: 무한한 크기의 LIFO 스택 메모리를 탑재하여 CFG를 정확히 인식하는 오토마타 모델.

</details>

- 생성 규칙의 좌변이 항상 단일 비단말($|A| = 1$)이므로 **주변 문맥과 독립적인 치환** 보장
- 재귀적 생성 규칙($E \to E + E \mid (E) \mid id$)을 통해 **임의 깊이의 중첩 구문 트리** 생성
- 동일 수식에 대해 연산자 우선순위 미정의 시 발생하는 **문법 모호성** 해결 필수

#### 한줄 요약

- 문맥 독립적 치환으로 무제한 유도를 수행하되, 동일 문자열에 2개 이상의 구문 트리가 생성되면 모호한 문법으로 분류한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **문법 4-튜플 모델($G = (V, \Sigma, R, S)$)**: 비단말 집합 $V$, 단말 집합 $\Sigma$, 생성 규칙 집합 $R$, 시작 기호 $S$로 구성된 문맥 자유 문법의 수학적 정의.

</details>

```text
[문맥 자유 문법 모델 (G)]
  │
  ├─ [기호 집합 정의부] (어휘 및 구문 범주)
  │     ├─ 비단말 기호 집합 V (구문 트리 내부 노드 정의)
  │     └─ 단말 기호 집합 Σ (잎 노드 구성 입력 토큰)
  │
  ├─ [생성 규칙 및 시작점] (치환 및 구문 출발)
  │     ├─ 생성 규칙 집합 R (재귀적 치환 관계 A -> α 정의)
  │     └─ 시작 기호 S (구문 유도의 최상위 출발점)
  │
  └─ [구문 유도 및 인식부] (트리 도출 및 인식 기계)
        ├─ 구문 트리 생성기 (좌단/우단 유도 트리 구축)
        └─ 푸시다운 오토마타 (LIFO 스택 기반 언어 인식)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 비단말 집합 V | 구문 트리 내부 노드를 구성하는 **구문 범주** 정의 |
| 단말 집합 Σ | 소스 코드의 잎 노드를 구성하는 **입력 토큰** 정의 |
| 생성 규칙 집합 R | 비단말 기호의 **재귀적 치환 관계($A \to \alpha$)** 정의 |
| 시작 기호 S | 전체 프로그램 구문 유도의 **최상위 출발점** 지정 |

#### 한줄 요약

- 비단말•단말•생성 규칙•시작 기호의 4튜플로 문맥 자유 문법을 정의한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **구문 분석(Parsing)**: 소스 코드 토큰 스트림으로부터 CFG 문법 규칙에 부합하는 구문 트리를 구축하는 컴파일러 2단계 프로세스.

</details>

```text
+------------------------------------------+
|  입력 토큰 스트림 (a1, a2, ... an) 진입  |
+--------------------+---------------------+
                     |
                     v
+------------------------------------------+
|  1. 시작 기호 S로부터 유도(Derivation) 개시|
+--------------------+---------------------+
                     |
                     v
           /--------------------\
          <   현재 유도 기호 판정 >
           \--------------------/
            |                  |
 비단말 (A) |                  | 단말 기호 (a)
            v                  v
[ 생성 규칙 A -> α 치환 ]   [ 입력 토큰과의 일치 검사 ]
            |                  |
            |           /--------------\
            |          <  토큰 일치?   > -- No --> [ 구문 오류 (Syntax Error) ]
            |           \--------------/
            |                  | Yes
            |                  v
            |           [ 입력 토큰 소비 및 다음 이동 ]
            |                  |
            +-------->---------+
                               |
                     /--------------------\
                    <  입력 및 유도 동시 소진? >
                     \--------------------/
                      |                  |
                Yes   |                  | No
                      v                  v
             [ 유효 구문 트리 반환 ]  [ 구문 분석 실패 ]
```

분기 결과: 현재 유도 기호가 비단말이면 생성 규칙으로 치환하고, 단말 기호가 입력 토큰과 일치하면 토큰을 소비하며, 입력과 유도 기호가 동시에 모두 소진되면 유효한 구문 트리를 확정 반환한다.

**동작 원리**:
1. **시작 기호 유도 개시**: 파서는 문법의 최상위 시작 기호 $S$를 구문 트리의 루트 노드로 초기화하고 유도를 개시한다.
2. **비단말 기호 규칙 치환**: 파스 트리 잎 노드에 비단말 기호 $A$가 나타나면 적용 가능한 생성 규칙 $A \to \alpha$를 선택하여 우변의 기호열로 치환하고 자식 노드로 확장한다.
3. **단말 기호 토큰 대조**: 유도된 기호가 단말 기호 $a$인 경우, 입력 토큰 스트림의 현재 심볼과 일치하는지 비교 검증(Match)한다.
4. **토큰 소비 및 전진**: 대조가 성공하면 해당 단말 토큰을 소비하고 입력 스트림의 다음 토큰으로 룩어헤드 포인터를 이동한다.
5. **구문 트리 완성 및 검증**: 입력 토큰 스트림의 끝(EOF)에 도달하고 모든 비단말 기호의 치환이 완료되면 최종 단일 구문 트리를 완성하여 반환한다.

#### 한줄 요약

- 하향식 또는 상향식으로 생성 규칙을 적용해 입력 토큰의 유도와 구문 트리를 구성한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **정규 문법(Regular Grammar, Type-3)**: $A \to aB \mid a$ 형태의 선형 규칙으로 유한 오토마타(DFA/NFA)가 인식하는 최하위 문법.
- **문맥 자유 문법(Context-Free Grammar, Type-2)**: $A \to \alpha$ 형태로 푸시다운 오토마타(PDA)가 인식하며 중첩 구문을 표현하는 문법.
- **문맥 의존 문법(Context-Sensitive Grammar, Type-1)**: $\alpha A \beta \to \alpha \gamma \beta$ 형태로 선형 유계 오토마타(LBA)가 인식하며 주변 문맥을 검증하는 문법.
- **선형 유계 오토마타(Linear Bounded Automaton, LBA)**: 입력 문자열 길이에 비례하는 유한한 테이프 공간만을 사용하는 비결정론적 튜링 머신 모델.

</details>

| 문법 종류 | 문맥 자유 문법 (CFG / Type-2) | 정규 문법 (Regular / Type-3) | 문맥 의존 문법 (CSG / Type-1) |
|:---|:---|:---|:---|
| 적용 기준 | 괄호 매칭, 블록 구문 등 **재귀 중첩 구조** | 식별자, 숫자 등 단순 **선형 어휘 패턴** | 변수 선언-사용 일치 등 **문맥 제약** |
| 핵심 특징 | **$A \to \alpha$ (좌변 단일 비단말)** | $A \to aB \mid a$ (선형 생성 규칙) | $\alpha A \beta \to \alpha \gamma \beta$ (주변 문맥 참조) |
| 인식 기계 | **푸시다운 오토마타 (PDA)** | **유한 오토마타 (DFA/NFA)** | **선형 유계 오토마타 (LBA)** |
| 한계 | 문법 모호성 및 파싱 충돌 위험 | 임의 깊이의 중첩/재귀 표현 불가 | 파싱 계산 복잡도 급증 ($O(2^n)$) |

#### 한줄 요약

- 유한 상태 패턴은 정규 문법, 중첩 구문은 CFG, 주변 문맥 제약은 문맥 의존 문법을 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **좌재귀 제거(Elimination of Left Recursion)**: 하향식 파서가 $A \to A\alpha$ 규칙에서 무한 루프에 빠지는 것을 방지하기 위해 우재귀 형태로 변환하는 기법.
- **좌인수분해(Left Factoring)**: 공통 접두사를 가진 규칙들을 묶어 파서의 룩어헤드 결정을 단순화하는 기법.
- **LL(1) 파싱(LL(1) Parsing)**: 입력을 왼쪽에서 오른쪽으로 읽고 최좌단 유도를 수행하며 1개 토큰을 미리 보고 파싱하는 하향식 기법.
- **패닉 모드 오류 복구(Panic-mode Error Recovery)**: 구문 오류 발생 시 동기화 토큰까지 입력을 건너뛰어 파싱을 재개하는 복구 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동일 수식에 대한 **문법 모호성** | 우선순위 및 결합 법칙을 반영한 **계층적 문법 재작성** | 고유한 단일 구문 트리 생성 보장 |
| 하향식 재귀 하강 파서의 **좌재귀 무한 루프** | 즉시 **좌재귀 제거** 및 우재귀 변환 공식 적용 | **LL(1) 파싱** 안정성 확보 |
| 파서 룩어헤드 선택 시 발생하는 **파싱 충돌** | **좌인수분해** 및 Lookahead($k$) 확장 | 결정적 파싱 테이블 구성 |
| 구문 오류 발생 시 파서 동기화 실패에 따른 연쇄 거짓 경고 발생 | 동기화 토큰(세미콜론 등) 기반 **패닉 모드 오류 복구** | 컴파일러 오류 진단 정확성 향상 |

#### 한줄 요약

- 좌재귀는 우재귀로 변환하고, 모호한 문법은 우선순위·결합 법칙 계층으로 재작성하며, 구문 오류 시에는 동기화 토큰 기반 패닉 모드로 연쇄 경고를 차단한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **컴파일러 프론트엔드 파이프라인**: 렉서(Lexer, 정규식/DFA) $\to$ 파서(Parser, CFG/LALR/LL) $\to$ 의미 분석기(Type Checker, 문맥 의존 검증)로 이어지는 계층적 구조.

</details>

- 프로그래밍 언어 명세(BNF/EBNF) 및 컴파일러 파서 제너레이터(Yacc/Bison, ANTLR)의 구문 정의 표준으로 정립되어 널리 활용되고 있으며, 향후 트리-시터(Tree-sitter) 등 점진적(Incremental) 파싱 및 오류 내성 복구 구조로 확장될 것으로 전망되고, 실무 엔지니어링에서는 연산자 우선순위 계층화를 통해 문법 모호성을 제거하고, 재귀 하강 파서의 무한 루프를 방지하기 위해 좌재귀 제거 및 좌인수분해를 사전 적용해야 한다.

#### 한줄 요약

- 재귀 하강 파서는 좌재귀와 모호성을 제거하고, 중첩 구문은 CFG로 표현한다.
