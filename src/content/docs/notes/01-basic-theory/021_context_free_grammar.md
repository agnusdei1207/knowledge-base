## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **CFG(Context-Free Grammar, 문맥 자유 문법)**: 좌변이 단일 비단말 기호(Single Non-terminal)로만 구성되어 주변 문맥과 무관하게 생성 규칙($A \to \alpha$)을 적용하는 촘스키 2형식 문법.
- **비단말 기호(Non-terminal Symbol, $V$ 또는 $N$)**: 다른 기호열로 추가 치환 가능한 구문 범주(Syntactic Category).
- **단말 기호(Terminal Symbol, $\Sigma$ 또는 $T$)**: 더 이상 치환되지 않고 소스 코드에 직접 나타나는 어휘 토큰(Token).
- **재귀 구문(Recursive Syntax)**: 괄호의 짝 맞춤, 수식의 연산자 중첩, 블록 제어문처럼 자기 자신을 재귀적으로 포함하는 계층적 구문 구조.

</details>

- 정의/개념: 단일 비단말을 문자열로 치환하는 생성 규칙을 재귀적으로 적용하여 임의 깊이의 중첩 구조를 표현하는 **문맥 자유 문법(CFG)**
- 배경/필요성: 유한 상태 기반 정규 문법의 메모리 한계로 인한 임의 깊이의 괄호 짝($a^n b^n$) 및 중첩 블록 구문 표현 불가 한계 극복 필요

#### 한줄 요약

- 단일 비단말 기호 좌변을 둔 생성 규칙 $A \rightarrow \alpha$의 재귀적 적용을 통해 임의 깊이의 중첩 구조를 기술

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **유도(Derivation)**: 시작 기호 $S$로부터 생성 규칙들을 반복 적용하여 최종 단말 문자열을 생성해 나가는 수학적 치환 과정.
- **모호성(Ambiguity)**: 하나의 단말 문자열에 대해 서로 다른 2개 이상의 유효한 구문 트리(Parse Tree) 또는 최좌단 유도(Leftmost Derivation)가 존재하는 문법적 불완전성.
- **푸시다운 오토마타(PDA, Pushdown Automaton)**: 무한한 크기의 LIFO 스택 메모리를 탑재하여 CFG를 정확히 인식하는 오토마타 모델.

</details>

- 생성 규칙의 좌변이 항상 단일 비단말($|A| = 1$)이므로 **주변 문맥과 독립적인 치환(Context-Free)** 보장
- 재귀적 생성 규칙($E \to E + E \mid (E) \mid id$)을 통해 **임의 깊이의 중첩 구문 트리(Parse Tree)** 생성
- 동일 수식에 대해 연산자 우선순위 미정의 시 발생하는 **문법 모호성(Ambiguity)** 해결 필수

#### 한줄 요약

- 문맥 독립적 치환으로 무제한 유도를 수행하되, 동일 문자열에 2개 이상의 구문 트리가 생성되면 모호한 문법으로 분류

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **문법 4-튜플 $G = (V, \Sigma, R, S)$**:
  - $V$ (또는 $N$): 비단말 기호들의 유한 집합.
  - $\Sigma$ (또는 $T$): 단말 기호(알파벳)들의 유한 집합 ($V \cap \Sigma = \emptyset$).
  - $R$ (또는 $P$): 생성 규칙들의 유한 집합 ($A \to \alpha$, 단 $A \in V, \alpha \in (V \cup \Sigma)^*$).
  - $S$: 시작 비단말 기호 ($S \in V$).

</details>

```text
[ 문맥 자유 문법 4-튜플 구조 ]
┌──────────────────────────────┐
│ 비단말 기호 집합 V (Variables)│ ── {E, T, F, Stmt, Block} 등 구문 범주
├──────────────────────────────┤
│ 단말 기호 집합 Σ (Terminals) │ ── {+, *, (, ), id, num} 등 어휘 토큰
├──────────────────────────────┤
│ 생성 규칙 집합 R (Rules)     │ ── A ──► α (A ∈ V, α ∈ (V ∪ Σ)*)
├──────────────────────────────┤
│ 시작 기호 S (Start Symbol)   │ ── 최상위 루트 구문 기호 (S ∈ V)
└──────────────────────────────┘
```

선의 의미: 비단말, 단말, 생성 규칙, 시작 기호 간의 4-튜플 수학적 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 비단말 집합 V | 구문 트리 내부 노드를 구성하는 **구문 범주** 정의 |
| 단말 집합 Σ | 소스 코드의 잎 노드를 구성하는 **입력 토큰** 정의 |
| 생성 규칙 집합 R | 비단말 기호의 **재귀적 치환 관계($A \to \alpha$)** 정의 |
| 시작 기호 S | 전체 프로그램 구문 유도의 **최상위 출발점** 지정 |

#### 한줄 요약

- 비단말•단말•생성 규칙•시작 기호의 4튜플로 문맥 자유 문법을 정의

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **구문 분석(Parsing)**: 소스 코드 토큰 스트림으로부터 CFG 문법 규칙에 부합하는 구문 트리를 구축하는 컴파일러 2단계 프로세스.

</details>

```text
입력 토큰 스트림 (w = t1 t2.. tn)
   │
   ▼
[ 1. 시작 기호 S에서 유도 개시 ]
   │
   ▼
유도 상태의 현재 기호 판별
├─ 비단말 기호 A (Non-terminal)
│  │
│  ▼
│  [ 2. 생성 규칙 적용 ] : A ──► α 로 치환 및 파스 트리 자식 노드 확장
│  │
│  └─ 유도 상태 기호 판별 반복
└─ 단말 기호 a (Terminal)
   │
   ▼
   [ 3. 입력 토큰 대조 (Match) ]
   ├─ 불일치: 구문 오류(Syntax Error) 보고 및 거부
   └─ 일치: 입력 토큰 소비 및 다음 기호로 이동
      │
      ▼
[ 4. 수용 및 파스 트리 완성 ]
├─ 입력 및 유도 기호 동시 소진 ⟹ [ 구문 트리(Parse Tree) 반환 ]
└─ 미소진 잔여 ⟹ [ 구문 분석 실패 ]
```

**동작 원리**

1. **시작 기호 설정**: 최상위 시작 기호 $S$를 루트 노드로 지정하여 유도 시작
2. **생성 규칙 적용**: 유도 문자열 내의 비단말 기호를 문법 규칙에 따라 우변 기호열로 치환하며 트리 확장
3. **입력 토큰 대조**: 유도된 단말 기호와 입력 토큰 스트림의 현재 심볼을 대조하여 일치 시 토큰 소비
4. **수용 및 트리 완성**: 모든 입력 토큰이 성공적으로 소비되고 비단말이 남지 않았을 때 완전한 구문 트리 반환

#### 한줄 요약

- 하향식 또는 상향식으로 생성 규칙을 적용해 입력 토큰의 유도와 구문 트리를 구성

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **촘스키 계층 구조(Chomsky Hierarchy)**:
  - 3형식(정규 문법): $A \to aB \mid a$, 유한 오토마타(DFA), 선형 패턴.
  - 2형식(문맥 자유): $A \to \alpha$, 푸시다운 오토마타(PDA), 중첩 구문.
  - 1형식(문맥 의존): $\alpha A \beta \to \alpha \gamma \beta$, 선형 유계 오토마타(LBA), 타입 검사/문맥 제약.
  - 0형식(무제약): $\alpha \to \beta$, 튜링 머신(TM), 계산 가능 언어.

</details>

| 비교 항목 | 문맥 자유 문법 (CFG / Type-2) | 정규 문법 (Regular / Type-3) | 문맥 의존 문법 (CSG / Type-1) |
|:---|:---|:---|:---|
| 적용 기준 | 괄호 매칭, 블록 구문 등 **재귀 중첩 구조** | 식별자, 숫자 등 단순 **선형 어휘 패턴** | 변수 선언-사용 일치 등 **문맥 제약** |
| 핵심 특징 | **$A \to \alpha$ (좌변 단일 비단말)** | $A \to aB \mid a$ (선형 생성 규칙) | $\alpha A \beta \to \alpha \gamma \beta$ (주변 문맥 참조) |
| 인식 기계 | **푸시다운 오토마타 (PDA)** | **유한 오토마타 (DFA/NFA)** | **선형 유계 오토마타 (LBA)** |
| 한계 및 위험 | 문법 모호성 및 파싱 충돌 위험 | 임의 깊이의 중첩/재귀 표현 불가 | 파싱 계산 복잡도 급증 ($O(2^n)$) |

#### 한줄 요약

- 유한 상태 패턴은 정규 문법, 중첩 구문은 CFG, 주변 문맥 제약은 문맥 의존 문법을 적용

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **좌재귀 제거(Elimination of Left Recursion)**: 하향식 파서(LL)가 $A \to A\alpha$ 규칙에서 무한 루프에 빠지는 것을 방지하기 위해 $A \to \beta A', A' \to \alpha A' \mid \varepsilon$ 형태로 변환하는 기법.
- **좌인수분해(Left Factoring)**: 공통 접두사를 가진 규칙($A \to \alpha\beta_1 \mid \alpha\beta_2$)을 $A \to \alpha A'$로 묶어 파서의 룩어헤드 결정을 단순화하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동일 수식에 대한 **모호한 문법(Dangling Else 등)** | 우선순위 및 결합 법칙을 반영한 **계층적 문법 재작성** | 고유한 단일 구문 트리 생성 보장 |
| 하향식 재귀 하강 파서의 **좌재귀(Left Recursion) 무한 루프** | 즉시 좌재귀 제거 및 우재귀 변환 공식 적용 | **LL(1) 파싱** 안정성 확보 |
| 파서 룩어헤드 선택 시 발생하는 **파싱 충돌(FIRST/FOLLOW)** | **좌인수분해(Left Factoring)** 및 Lookahead($k$) 확장 | 결정적 파싱 테이블 구성 |
| 구문 오류 발생 시 파서 동기화 실패에 따른 연쇄 거짓 경고 발생 | 동기화 토큰(세미콜론 등) 기반 **패닉 모드 오류 복구** | 컴파일러 오류 진단 정확성 향상 |

#### 한줄 요약

- 좌재귀는 우재귀로 변환하고, 모호한 문법은 우선순위·결합 법칙 계층으로 재작성하며, 구문 오류 시에는 동기화 토큰 기반 패닉 모드로 연쇄 경고를 차단한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **컴파일러 프론트엔드 파이프라인**: 렉서(Lexer, 정규식/DFA) $\to$ 파서(Parser, CFG/LALR/LL) $\to$ 의미 분석기(Type Checker, 문맥 의존 검증)로 이어지는 계층적 구조.

</details>

- 재귀적 중첩 구문 분석은 **문맥 자유 문법(CFG)**, 선형 토큰 매칭은 **정규 문법**, 의미적 문맥 검증은 **문맥 의존 문법** 선택

#### 한줄 요약

- 재귀 하강 파서는 좌재귀와 모호성을 제거하고, 중첩 구문은 CFG로 표현
