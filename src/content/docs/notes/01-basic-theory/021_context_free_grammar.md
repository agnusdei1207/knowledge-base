## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **문맥 자유 문법(Context-Free Grammar, CFG)**: 좌변이 단일 비단말인 생성 규칙으로 재귀적 중첩 구문을 표현하는 문법이다.
- **비단말 기호**: 생성 규칙으로 더 치환할 수 있는 구문 범주이다.
- **재귀 구문**: 같은 구문 범주를 내부에 다시 포함해 임의 깊이로 중첩되는 구조이다.
- **형식 문법(Formal Grammar)**: 알파벳과 생성 규칙으로 유효한 문자열 구조를 정의하는 체계이다.

</details>

- 정의/개념: 단일 비단말을 문자열로 치환하는 규칙을 재귀 적용해 중첩 구문을 표현하는 **문맥 자유 문법**이다.
- 배경/필요성: 유한 상태 기반 정규 문법만으로는 임의 깊이의 괄호와 재귀적 프로그램 구문을 표현할 수 없다.

#### 한줄 요약

- 단일 비단말 기호 좌변을 둔 생성 규칙 $A \rightarrow \alpha$의 재귀적 적용을 통해 임의 깊이의 중첩 구조를 기술한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **유도(Derivation)**: 생성 규칙을 반복 적용해 시작 기호를 단말열로 바꾸는 과정이다.
- **단말열(Terminal String)**: 비단말이 모두 치환되어 단말 기호만 남은 문자열이다.
- **모호성(Ambiguity)**: 하나의 문자열에서 둘 이상의 구문 트리가 생성되어 해석이 달라지는 성질이다.
- **단일 비단말 치환**: 생성 규칙 좌변의 비단말 하나를 우변 기호열로 바꾸는 작업이다.

</details>

- 좌변의 **단일 비단말 치환**으로 주변 문맥과 무관한 규칙을 적용한다.
- 재귀 규칙의 반복 **유도**로 무제한 중첩 단말열을 생성한다.
- 동일 문자열의 복수 구문 트리에 따른 **모호성**이 핵심이다.

#### 한줄 요약

- 문맥 독립적 치환으로 무제한 유도를 수행하되, 동일 문자열에 2개 이상의 구문 트리가 생성되면 모호한 문법으로 분류한다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **문법 4튜플 $G=(N,\Sigma,P,S)$**: 비단말•단말•생성 규칙•시작 기호로 CFG를 정의한 묶음이다.
- **파서(Parser)**: 입력 토큰이 문법에 맞는지 검사하고 구문 트리로 바꾸는 분석기이다.
- **구문 트리(Parse Tree)**: 생성 규칙의 적용 관계를 부모•자식 구조로 나타낸 트리이다.

</details>

```text
문맥 자유 문법 G
├─ 비단말 집합 N
├─ 단말 집합 Σ
├─ 생성 규칙 집합 P
└─ 시작 기호 S
```

선의 의미: 문맥 자유 문법을 정의하는 4튜플의 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 비단말 집합 N | **비단말 집합 N**의 구문 범주 정의 |
| 단말 집합 Σ | **단말 집합 Σ**의 입력 기호 정의 |
| 생성 규칙 집합 P | **생성 규칙 집합 P**의 치환 관계 정의 |
| 시작 기호 S | **시작 기호 S**를 전체 유도의 출발점으로 지정 |

#### 한줄 요약

- 비단말•단말•생성 규칙•시작 기호의 4튜플로 문맥 자유 문법을 정의한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **유도 상태**: 생성 규칙을 적용하는 과정에서 현재 남아 있는 단말과 비단말의 기호열이다.
- **입력 토큰 스트림**: 파서가 문법의 단말과 비교하도록 토큰을 순서대로 제공하는 입력이다.
- **비단말 치환**: 선택한 생성 규칙의 좌변 비단말을 우변 기호열로 바꾸는 작업이다.
- **생성 규칙(Production Rule)**: 비단말을 단말과 비단말의 기호열로 치환하는 규칙이다.
- **수용**: 입력 토큰 전체가 문법 규칙에 맞는 완성 유도를 이룬 상태이다.

</details>

```text
시작 기호 S•입력 토큰
        │
        ▼
1. 현재 기호 판별
        ├─ 비단말
        │    │
        │    ▼
        │  2. 생성 규칙 적용
        │    └── 유도 상태에 기호가 남으면 반복
        │
        └─ 단말
             │
             ▼
           3. 입력 토큰 대조
             ├─ 불일치: 거부
             └─ 일치: 다음 기호 판별
                         │
                         ▼
                 4. 수용 상태 판정
                         ├─ 입력•유도 소진: 구문 트리 반환
                         └─ 미소진: 거부
```

### 동작 원리

- **1. 현재 기호 판별**: 유도 상태의 비단말•단말을 구분한다.
- **2. 생성 규칙 적용**: 비단말 치환과 구문 트리 확장이다.
- **3. 입력 토큰 대조**: 단말 일치 시 소비, 불일치 시 오류이다.
- **4. 수용 상태 판정**: 입력 소진과 완성 유도 여부를 확인한다.

#### 한줄 요약

- Top-down / Bottom-up Parsing 방식으로 생성 규칙을 적용하여 유도 Sequence를 도출하고 구문 트리를 구축한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **정규 문법(Regular Grammar)**: 한 방향의 선형 생성 규칙으로 유한 상태 패턴을 표현하는 문법이다.
- **문맥 의존 문법(Context-Sensitive Grammar)**: 비단말 주변 기호에 따라 규칙 적용 여부가 달라지는 문법이다.
- **파싱 충돌(Parsing Conflict)**: 같은 입력 위치에서 적용할 문법 규칙을 하나로 결정하지 못하는 상태이다.
- **인식 계산량**: 입력 문자열이 문법에 속하는지 판정하는 데 필요한 시간과 메모리이다.

</details>

| 형식 문법 | 문맥 자유 문법 | 정규 문법 | 문맥 의존 문법 |
|:---|:---|:---|:---|
| 적용 기준 | 입력에 따라 **중첩 깊이** 증가 | **유한 상태**로 패턴 구분 가능 | 주변 기호가 **규칙 적용** 여부 결정 |
| 핵심 특징 | **재귀적 중첩** 구조 표현 | **선형 반복**•선택 표현 | **주변 문맥** 제약 표현 |
| 한계 | **모호성**에 따른 파싱 충돌 | 재귀 구문 표현 불가 | 일반 문자열의 **인식 계산량** 증가 |

#### 한줄 요약

- 정규 문법(Finite Automata), CFG(Pushdown Automata), CSG(Linear Bounded Automata)로 Chomsky Hierarchy의 표현력과 계산 복잡도를 차등 적용한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **좌재귀(Left Recursion)**: 비단말이 유도 결과의 맨 왼쪽에 다시 나타나 하향식 파서를 무한 호출시키는 재귀이다.
- **좌인수분해(Left Factoring)**: 여러 생성 규칙의 공통 접두부를 묶어 다음 입력으로 규칙을 결정하게 하는 문법 변환이다.
- **FIRST 집합**: 비단말에서 처음 나올 수 있는 단말의 집합이다.
- **FOLLOW 집합**: 비단말 바로 뒤에 올 수 있는 단말의 집합이다.
- **동기화 토큰(Synchronizing Token)**: 오류 뒤 파서가 입력 처리를 다시 시작할 위치를 찾는 기준 토큰이다.
- **LL 파싱(Left-to-right Leftmost Derivation Parsing, LL)**: 입력을 왼쪽부터 읽고 좌측 유도를 구성하는 하향식 파싱 방식이다.
- **파싱표(Parsing Table)**: 현재 비단말과 다음 입력 토큰으로 적용할 생성 규칙을 결정하는 표이다.
- **오류 복구**: 문법 오류 뒤 동기화 지점으로 이동해 후속 입력 분석을 계속하는 처리이다.
- **문법 재작성**: 생성 언어를 보존하면서 모호성•좌재귀•공통 접두부를 제거하도록 규칙을 변환하는 작업이다.
- **진단 연쇄**: 하나의 구문 오류가 뒤 토큰의 연속된 오류 보고를 유발하는 현상이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 동일 문자열의 **복수 구문 트리** | 우선순위•결합 규칙으로 **문법 재작성** | **모호성** 제거 |
| 하향식 파서의 **좌재귀** 호출 | 좌재귀 제거•**좌인수분해** | **LL 파싱** 가능성 확보 |
| 같은 입력 위치의 **파싱 충돌** | **FIRST•FOLLOW**로 파싱표 검증 | 적용 규칙을 하나로 결정 |
| 오류 입력의 **진단 연쇄** | 동기화 토큰 기반 **오류 복구** | 후속 오류 위치의 정확도 향상 |
| 컴파일러의 **재귀 구문** | CFG로 괄호•블록 **구문 트리** 구성 | 구문 구조 보존 |

#### 한줄 요약

- 좌재귀 제거, 좌인수분해, FIRST/FOLLOW 집합 기반의 파싱표 구축으로 LL/LR 파싱 충돌을 해소한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **문법 선택 기준**: 규칙 적용이 중첩 구조만 필요한지 주변 기호까지 의존하는지 구분하는 기준이다.

</details>

- **문법 선택 기준**에 따라 중첩 구문은 CFG, 주변 기호에 의존하면 **문맥 의존 문법**을 선택한다.

#### 한줄 요약

- Recursive Descent 파서 구축 시 Left-recursion 억제 및 모호성 제거를 위한 Grammar Refactoring을 필수 집행 체계 적용
