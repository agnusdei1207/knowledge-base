## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴파일러**: 소스 프로그램의 의미를 보존하며 목적 코드로 변환하는 번역기이다.
- **목적 코드**: 프로세서가 실행하거나 링커가 결합할 수 있도록 만든 기계 명령 코드이다.
- **언어 번역기**: 한 프로그래밍 언어의 의미를 보존해 다른 코드 형식으로 변환하는 프로그램이다.
- **이식성**: 같은 소스나 중간 표현을 여러 타깃 기계에서 사용할 수 있는 성질이다.

</details>

- 정의/개념: 소스 프로그램을 분석하여 중간 표현으로 변환하고 의미 보존 최적화와 코드 생성을 거쳐 목적 코드로 번역하는 **언어 번역기**
- 배경/필요성: 소스 언어·타깃 기계 조합별 변환기 개별 구축 시 코드 생성·최적화 중복으로 **이식성** 저하

#### 한줄 요약
- 소스 코드를 기계 독립 중간 표현(IR)으로 변환한 뒤 각 타깃 기계 전용 목적 코드로 생성하는 구조이다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **전단부(Front End)**: 소스 언어를 분석해 중간 표현을 만드는 부분이다.
- **후단부(Back End)**: 중간 표현을 타깃 기계 코드로 변환하는 부분이다.
- **결정적 유한 오토마타(Deterministic Finite Automaton, DFA)**: 문자마다 하나의 다음 상태로 토큰 패턴을 인식하는 모델이다.
- **중간 표현(Intermediate Representation, IR)**: 최적화와 코드 생성에 사용하는 기계 독립 내부 코드이다.
- **정규표현식(Regular Expression)**: 토큰의 문자 패턴을 기술하는 형식 표현이다.
- **LL 파서(Left-to-right Leftmost Derivation Parser, LL Parser)**: 입력을 왼쪽부터 읽으며 좌측 유도를 구성하는 파서이다.
- **LR 파서(Left-to-right Rightmost Derivation Parser, LR Parser)**: 입력을 왼쪽부터 읽으며 우측 유도의 역순을 구성하는 파서이다.
- **의미 동등성**: 번역 전후 프로그램이 같은 입력에서 같은 결과를 내는 성질이다.

</details>

- **전단부**•중간 표현•**후단부** 분리 기반 단계적 번역 구조
- 정규표현식•**DFA** 토큰화 및 LL•**LR 파서** 구문 분석
- **의미 동등성** 보존 공통 IR 기반 이식성 확보

#### 한줄 요약
- 문자 흐름이 토큰열, AST, IR로 차례로 변환되며 각 분석 단계에서 오류가 진단되는 구조이다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **심볼 테이블**: 식별자의 타입•범위•주소 정보를 저장하는 표이다.
- **최적화기**: 실행 의미를 유지하며 IR의 연산 수나 자원 사용을 줄이는 모듈이다.
- **레지스터 할당**: 중간값을 제한된 프로세서 레지스터에 배치하는 후단부 작업이다.
- **어휘 분석(Lexical Analysis)**: 문자를 토큰으로 나누는 전단 단계이다.
- **구문 분석(Syntax Analysis)**: 토큰에서 문장 구조를 만드는 전단 단계이다.
- **의미 분석(Semantic Analysis)**: 타입•선언 규칙을 검사하는 전단 단계이다.
- **명령 선택**: 중간 표현의 연산을 타깃 프로세서 명령으로 대응시키는 작업이다.

</details>

```text
[컴파일러]
    |
    +-- [전단부]
    +-- [심볼 테이블]
    +-- [중간 표현]
    +-- [최적화기]
    `-- [후단부]
```

선의 의미: 컴파일러의 전단•IR•최적화•후단과 심볼 정보의 정적 구성 관계

| 구성요소 | 책임 |
|:---|:---|
| 전단부 | 소스의 **어휘 분석**•**구문 분석**•**의미 분석**과 IR 생성 |
| 심볼 테이블 | 식별자의 타입•범위•주소 정보 저장 |
| 중간 표현 | 모듈을 잇는 기계 독립 코드 제공 |
| 최적화기 | **의미 동등성**을 보존하며 IR 연산 최적화 |
| 후단부 | 명령 선택•**레지스터 할당**으로 목적 코드 생성 |

#### 한줄 요약
- 전단부 분석 단계와 심볼 테이블이 소스를 검증하고, IR이 최적화를 거쳐 타깃 목적 코드로 생성되는 구조이다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **토큰**: 어휘 분석기가 소스 문자에서 구분해 내는 최소 어휘 단위이다.
- **추상 구문 트리(Abstract Syntax Tree, AST)**: 프로그램의 연산과 문장 구조를 나타내는 트리이다.
- **토큰화(Tokenization)**: 소스 문자 흐름을 식별자•키워드•연산자 등의 토큰으로 나누는 작업이다.
- **어휘 분석•토큰화**: 소스의 문자 흐름을 최소 어휘 단위인 토큰으로 분리하는 단계이다.
- **구문 분석•AST 생성**: 토큰 배열이 문법에 맞는지 검사하고 추상 구문 트리를 만드는 단계이다.
- **의미 분석•IR 생성**: 타입•선언 규칙을 검사하고 기계 독립 중간 표현을 만드는 단계이다.
- **의미 보존 IR 최적화**: 프로그램 결과를 바꾸지 않으면서 중간 표현의 연산과 자원 사용을 줄이는 단계이다.
- **타깃 목적 코드 생성**: 명령 선택과 레지스터 할당으로 대상 기계의 목적 코드를 만드는 단계이다.

</details>

```text
[소스 프로그램]
      |
      v
1. 어휘 분석•토큰화
      |
      v
2. 구문 분석•AST 생성
      |
      v
3. 의미 분석•IR 생성
      |
      v
4. 의미 보존 IR 최적화
      |
      v
5. 타깃 목적 코드 생성
      |
      v
[목적 코드]
```

### 동작 원리

- **1. 어휘 분석•토큰화**: 문자 흐름의 토큰 분리
- **2. 구문 분석•AST 생성**: 문법 기반 프로그램 구조 구성
- **3. 의미 분석•IR 생성**: 타입•선언 검사 및 중간 표현 생성
- **4. 의미 보존 IR 최적화**: 실행 의미 유지 연산 축소
- **5. 타깃 목적 코드 생성**: 명령 선택•레지스터 할당 수행

#### 한줄 요약
- 소스 코드가 전단부 분석과 IR 최적화를 거쳐 타깃 기계의 목적 코드로 생성되는 흐름이다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **인터프리터**: 소스를 구문 단위로 읽고 즉시 해석해 실행하는 방식이다.
- **적시 컴파일러(Just-In-Time Compiler, JIT Compiler)**: 실행 중 자주 쓰는 코드를 기계어로 번역하는 방식이다.
- **핫 코드(Hot Code)**: 실행 빈도가 높아 최적화할 코드이다.
- **웜업(Warm-up)**: JIT 최적화 전의 느린 초기 구간이다.
- **고정 바이너리**: 실행 전에 특정 타깃 기계용으로 완전히 번역한 실행 파일이다.
- **재빌드(Rebuild)**: 소스나 타깃이 바뀐 뒤 목적 코드와 실행 파일을 다시 생성하는 작업이다.
- **빌드 시점**: 프로그램을 실행하기 전에 소스 코드를 번역하고 실행 파일을 만드는 시점이다.
- **실행 시점**: 사용자가 프로그램을 구동해 명령을 수행하는 시점이다.

</details>

| 실행 방식 | 컴파일러 | 인터프리터 | JIT 컴파일러 |
|:---|:---|:---|:---|
| 적용 기준 | 반복 실행할 **고정 바이너리**가 필요한 경우 | 대화형 실행과 즉시 수정 반영이 필요한 경우 | 장시간 실행 중 **핫 코드** 최적화가 필요한 경우 |
| 핵심 특징 | 실행 전 전체 번역으로 목적 코드 산출 | 구문 단위로 즉시 해석해 실행 | 실행 중 **핫 코드**만 기계어 번역 |
| 한계 | 타깃별 **재빌드** 비용 | 반복 해석에 따른 실행 속도 저하 | **웜업** 지연•메모리 증가 |

> 요약: 번역 비용을 **빌드 시점**•실행 시점 중 어디에 둘지 선택

#### 한줄 요약
- 컴파일러는 소스 전체를 빌드 시점에 목적 코드로 변환하고, 인터프리터는 구문 단위로 즉시 해석하며, JIT은 실행 중 핫 코드만 기계어로 컴파일하는 구조이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **오컴파일**: 컴파일은 성공했지만 번역 오류로 원래 프로그램과 다른 결과가 나오는 문제이다.
- **동기화 토큰**: 구문 오류 뒤 파서가 분석을 다시 시작하는 기준 구분자이다.
- **프로파일 캐시**: 이전 실행의 호출•반복 빈도를 저장해 다음 JIT 판단에 재사용하는 저장소이다.
- **최적화 패스(Optimization Pass)**: IR을 순회하며 특정 코드 변환을 적용하는 단계이다.
- **후단부 회귀 테스트**: 타깃 코드 생성 변경이 기존 동작과 품질을 깨뜨리지 않는지 반복 확인하는 시험이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 최적화 전후 실행 결과 불일치 | 변환별 의미 동등성 테스트•문제 **최적화 패스** 비활성화 | **오컴파일** 방지 |
| 한 오류 뒤 진단이 연쇄 폭증 | **동기화 토큰** 기반 오류 복구 | 유효한 후속 오류 진단 유지 |
| 타깃별 코드 품질•정확성 차이 | **후단부 회귀 테스트**와 타깃별 검증 | **이식성**•코드 생성 신뢰성 확보 |
| JIT 초기 응답 지연 | 핫 코드 임계값•**프로파일 캐시** 조정 | **웜업** 시간 단축•핫 코드 성능 유지 |

#### 한줄 요약
- 최적화 전후 실행 결과가 불일치하면 의미 동등성을 위반한 최적화 패스를 비활성화하는 과정이다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **배포 판정 기준**: 번역 전후 의미 동등성과 타깃별 코드 생성 정확성을 확인하는 기준이다.

</details>

- **의미 동등성**과 타깃별 코드 생성 정확성 확인 후 후단부•**최적화 패스** 배포

#### 한줄 요약
- 새 타깃은 후단부를 교체하고, 의미 동등성을 위반하는 최적화 패스는 비활성화한다.
