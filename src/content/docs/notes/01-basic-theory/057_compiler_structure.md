## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **컴파일러(Compiler)**: 고급 프로그래밍 언어로 작성된 원시 코드를 의미를 보존하며 타깃 아키텍처의 기계어로 번역하는 시스템 소프트웨어.
- **중간 표현(Intermediate Representation, IR)**: 소스 언어와 타깃 기계어 사이에서 기계 독립적인 최적화를 수행하기 위해 사용하는 표준화된 코드 형태.
- **이식성(Portability)**: 하나의 소스 코드나 중간 표현을 다양한 하드웨어 및 운영체제 상에서 재사용할 수 있는 능력.

</details>

- 정의/개념: 고급 프로그래밍 언어의 원시 코드를 **어휘·구문·의미 분석을 통해 중간 표현으로 변환하고 최적화하여 타깃 기계어 코드로 번역**하는 시스템 소프트웨어
- 배경/필요성: 언어와 타깃을 직접 잇는 번역기는 $M$개 언어와 $N$개 기종에 대해 $M \times N$벌을 따로 만드는 **기종별 중복 개발** 비용을 치르므로, 둘 사이에 기계 독립적인 중간 표현 계층을 세워 비용을 프런트엔드 $M$개와 백엔드 $N$개의 합으로 낮추고 공통 최적화도 그 한 곳에 모음

#### 한줄 요약

- 중간 표현을 한 겹 끼워 조합 폭발을 덧셈으로 바꾸는 구조이므로, IR이 담아내지 못하는 언어 특성은 그 이득 밖에 남는다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **어휘 분석(Lexical Analysis)**: 문자 스트림을 정규 표현식 기반의 의미 있는 최소 단위인 토큰(Token)으로 분할하는 단계.
- **구문 분석(Syntax Analysis)**: 토큰 스트림을 문맥 자유 문법(CFG)에 따라 계층적 구문 트리(AST)로 파싱하는 단계.
- **의미 분석(Semantic Analysis)**: 구문 트리를 기반으로 타입 검사, 변수 선언 유효성 등 정적 의미 규칙을 검증하는 단계.

</details>

- **Front-End(분석)·Back-End(합성)** 분리 기반 $M \times N \to M + N$ 컴파일러 확장성 달성
- 정규 문법(유한 오토마타) 기반 **어휘 분석** 및 문맥 자유 문법(푸시다운 오토마타) 기반 **구문 분석**
- 타깃 독립적 **중간 표현(IR)** 기반 공통 루프·데이터 흐름 최적화 수행

#### 한줄 요약

- 프런트엔드 분석과 백엔드 합성을 분리하고 중간 표현을 통해 최적화 및 타깃 기계어 생성을 수행

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **추상 구문 트리(Abstract Syntax Tree, AST)**: 소스 코드의 문법 구조를 추상화하여 연산자와 피연산자의 관계를 계층적으로 표현한 트리.
- **심볼 테이블(Symbol Table)**: 변수, 함수, 클래스의 식별자 이름, 자료형, 스코프, 메모리 위치 정보를 관리하는 중앙 저장소.

</details>

```text
[ 컴파일러 ]
├── [ 프런트엔드 ]
│   ├── [ 어휘 분석기 ]
│   ├── [ 구문 분석기 ]
│   └── [ 의미 분석기 ]
├── [ 심볼 테이블 ]
└── [ 백엔드 ]
    ├── [ 최적화기 ]
    └── [ 코드 생성기 ]
```

선의 의미: 컴파일러가 소유한 분석·공유 저장소·합성 구성요소

| 구성요소 | 책임 |
|:---|:---|
| 어휘 분석기(Lexer) | 문자열 스트림을 정규식 기반 **토큰(Token) 시퀀스로 분할** |
| 구문 분석기(Parser) | 문법 규칙(CFG)을 적용하여 **추상 구문 트리(AST) 구축** |
| 의미 분석기(Semantic) | **타입 일치성, 스코프 유효성, 형 변환** 등 정적 의미 규칙 검증 |
| 심볼 테이블(Symbol) | 식별자의 타입, 위치, 유효 범위를 **전 단계에 걸쳐 통합 관리** |
| 최적화기(Optimizer) | 데드 코드 제거, 루프 불변식 이동 등 **실행 시간 및 메모리 최적화** |
| 코드 생성기(Code Gen) | 중간 표현을 타깃 CPU의 **명령어 선택 및 레지스터 할당 기계어로 변환** |

#### 한줄 요약

- 렉서, 파서, 의미 분석기의 프런트엔드와 심볼 테이블, 최적화기, 코드 생성기의 백엔드로 구성

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **3-주소 코드(Three-Address Code, TAC)**: 각 명령어가 최대 하나의 연산자와 3개의 주소(두 피연산자, 한 결과)로 구성된 표준 선형 중간 표현.

</details>

```text
원시 소스 코드 문자열
          │
          ▼
[ 1. 토큰화 ]
          │
          ▼
[ 2. 파싱 및 AST 생성 ]
          │
          ▼
[ 3. 정적 타입 및 스코프 검증 ]
          │
          ▼
[ 4. 3-주소 중간 코드 생성 및 최적화 ]
          │
          ▼
[ 5. 타깃 어셈블리 생성 ]
          │
          ▼
기계어 출력
```

**동작 원리**

1. **토큰화**: 유한 오토마타를 구동하여 소스 문자열을 토큰 단위로 분할하고 주석 제거
2. **파싱 및 AST 생성**: 푸시다운 오토마타 파서가 문법을 검증하고 AST 노드 결합
3. **정적 타입 및 스코프 검증**: 연산자 간 타입 호환성과 선언되지 않은 식별자 사용 여부 검증
4. **3-주소 중간 코드 생성 및 최적화**: 선형 IR을 생성하고 제어 흐름 및 데이터 흐름 분석을 통해 최적화
5. **타깃 어셈블리 생성**: 레지스터 할당을 거쳐 타깃 명령어 선택

#### 한줄 요약

- 문자열을 토큰화하고 AST를 만들어 의미를 검증한 후 중간 코드를 최적화하여 기계어로 출력

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하향식 파싱(LL Parser)**: 루트에서 리프로 내려가며 최좌단 유도를 수행하는 직관적 파서.
- **상향식 파싱(LR/LALR Parser)**: 토큰에서 루트로 시프트-리듀스 축소를 수행하는 강력한 범용 파서.

</details>

| 파싱 방식 (Parsing) | 하향식 파싱 (LL Parser) | 상향식 파싱 (LR/LALR Parser) |
|:---|:---|:---|
| 적용 기준 | **구현 단순성** 및 수작업 재귀 하강 파서 제작 시 | **복잡한 범용 프로그래밍 언어 문법** 및 파서 생성기 사용 시 |
| 핵심 특징 | 루트에서 시작해 **리프로 분기하는 하향식 유도** | 리프 토큰에서 시작해 **루트로 축소(Reduce)하는 상향식 파싱** |
| 한계 | **좌재귀(Left Recursion) 문법 처리 불가** | 파싱 테이블 크기 증가 및 **수작업 구현 난이도 극상** |

#### 한줄 요약

- 단순한 문법과 수작업 구현은 LL 파서, 강력한 범용 언어 지원은 LR/LALR 파서를 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **좌재귀(Left Recursion)**: 문법 규칙 $A \to A\alpha$처럼 비단말 기호가 자기 자신을 가장 왼쪽에 다시 호출하여 LL 파서에서 무한 루프를 유발하는 현상.
- **레지스터 스필(Register Spill)**: 사용 가능한 물리 레지스터보다 필요한 변수 수가 많아 변수를 스택 메모리로 임시 대피시키는 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 하향식 파싱 시 좌재귀 규칙에 의한 **파서 무한 재귀 루프** | **좌재귀 제거(Left Recursion Elimination) 및 좌인수분해** | 결정론적 LL(1) 파싱 가능 구조로 문법 정규화 |
| 공격적 컴파일러 최적화로 인한 **소스-바이너리 디버깅 불가** | **최적화 수준 플래그 분리(`-O0` 디버그 vs `-O3` 릴리즈)** | 개발 생산성 및 런타임 실행 성능의 분리 달성 |
| 복잡한 수식 연산 시 물리 레지스터 부족으로 **메모리 스필 발생** | **간섭 그래프 채색(Graph Coloring) 기반 레지스터 할당** | 메모리 접근 최소화 및 CPU 레지스터 활용 극대화 |

#### 한줄 요약

- 좌재귀는 문법 변환으로 제거하고, 디버깅은 최적화 레벨을 분리하며, 레지스터 부족은 그래프 채색법으로 해결

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **LLVM(Low Level Virtual Machine)**: 모듈형 컴파일러 인프라로 공통 LLVM IR을 기반으로 다양한 언어 프런트엔드와 하드웨어 백엔드를 플러그인 형태로 연결.

</details>

- 언어·타깃 확장 시 **LLVM IR** 기반 프런트·백엔드 모듈화 선택

#### 한줄 요약

- 표준 중간 표현(IR)을 중심으로 분석과 생성을 모듈 분리하는 컴파일러 아키텍처를 수립
