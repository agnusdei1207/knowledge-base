## 미리 알고가기

- **컴파일러(Compiler)**: 소스 프로그램의 의미를 보존하며 목적 코드로 변환하는 번역기
- **인터프리터(Interpreter)**: 소스를 읽으며 즉시 실행하는 번역•실행기
- **적시 컴파일(Just-In-Time Compilation, JIT)**: 프로그램 실행 중 자주 사용하는 코드를 기계어로 컴파일하고 재사용하여 실행 성능을 높이는 방식
- **핫 코드(Hot Code)**: 실행 빈도가 높아 JIT 최적화 대상으로 선택된 코드
- **웜업 구간(Warm-up)**: JIT 최적화 전의 느린 실행 초기 구간
- **목적 코드(Object Code)**: 프로세서가 실행하거나 링커가 결합할 수 있도록 컴파일러가 만든 기계 명령 코드
- **토큰(Token)**: 어휘 분석기가 만드는 최소 어휘 단위
- **정규표현식(Regular Expression)**: 토큰 문자 패턴을 정의하는 규칙
- **결정적 유한 오토마타(Deterministic Finite Automaton, DFA)**: 각 상태와 입력 기호에 대해 하나의 다음 상태가 결정되며, 어휘 분석에서 토큰 패턴을 인식하는 계산 모델
- **추상 구문 트리(Abstract Syntax Tree, AST)**: 프로그램의 연산•문장 구조를 나타낸 트리
- **심볼 테이블(Symbol Table)**: 식별자 타입•범위•주소 정보 저장
- **중간 표현(Intermediate Representation, IR)**: 최적화•코드 생성에 쓰는 기계 독립 내부 코드
- **어휘•구문•의미 분석(Lexical•Syntax•Semantic Analysis)**: 어휘 분석은 문자를 토큰으로, 구문 분석은 토큰을 AST로 만들고 의미 분석은 타입•선언 규칙을 검사하는 단계
- **식별자•타입•범위(Identifier•Type•Scope)**: 식별자는 변수•함수 이름, 타입은 값의 종류와 연산 규칙, 범위는 이름을 참조할 수 있는 코드 영역
- **전단부•후단부(Front-end•Back-end)**: 언어 분석과 타깃 코드 생성 단계의 경계
- **최적화기(Optimizer)**: 실행 의미를 유지하며 중간 표현의 연산 수나 자원 사용을 줄이는 컴파일러 모듈
- **최적화 패스(Optimization Pass)**: 중간 표현을 한 번 순회하며 특정 중복 연산 제거•코드 이동 등의 변환을 적용하는 단계
- **레지스터 할당(Register Allocation)**: 중간값을 제한된 프로세서 레지스터에 배치하는 후단부 작업
- **동기화 토큰(Synchronizing Token)**: 구문 오류 뒤 파서가 분석을 다시 시작하는 기준 구분자
- **통합 개발 환경(Integrated Development Environment, IDE)**: 소스 코드 편집•빌드•실행•디버깅 기능을 하나의 도구에 통합한 개발 환경
- **좌측 입력•최좌단 유도(Left-to-right, Leftmost Derivation, LL) 파서**: 입력을 왼쪽부터 읽고 최좌단 유도를 구성하며 시작 기호에서 생성 규칙을 전개하는 하향식 파서
- **좌측 입력•최우단 유도 역순(Left-to-right, Rightmost Derivation in Reverse, LR) 파서**: 입력을 왼쪽부터 읽고 최우단 유도의 역순으로 토큰을 문법 규칙에 환원하는 상향식 파서
- **오컴파일(Miscompilation)**: 컴파일은 완료됐지만 번역 과정의 오류로 원래 프로그램과 다른 실행 결과를 만드는 문제
- **프로파일 캐시(Profile Cache)**: 이전 실행에서 수집한 코드별 호출•반복 빈도를 저장해 다음 JIT 최적화 판단에 재사용하는 저장소

## Ⅰ. 개요

- 정의/개념: 고급 언어를 **목적 코드**로 변환하는 **번역기**
- 배경/필요성: 언어와 기계별 변환을 분리해 **이식성** 확보

### 쉽게 이해하기 (학습용)
- 컴파일러는 소스를 공통 IR로 바꾼 뒤 타깃별 후단부에서 기계 명령으로 번역한다.

## Ⅱ. 특징

- **전단부**•중간 표현•**후단부**로 분리된 단계적 번역 구조
- 변환 전후 프로그램 **의미 동등성** 보존
- 공통 **IR** 기반의 소스 언어•타깃 기계 **독립성**

### 쉽게 이해하기 (학습용)
- 토큰•AST•IR을 차례로 확인해 의미가 어긋난 번역 단계를 찾는다.

## Ⅲ. 구조 및 구성요소

```mermaid
block
    columns 3
    FE["전단부"]
    ST["심볼 테이블"]
    IR["중간 표현"]
    OPT["최적화기"]
    BE["후단부"]
    space
```

| 구성요소 | 책임 |
|:---|:---|
| 전단부 | 소스의 **어휘•구문•의미 분석**과 IR 생성 |
| 심볼 테이블 | 식별자의 **타입•범위•주소** 정보 저장 |
| 중간 표현 | 모듈을 잇는 **기계 독립 코드** 제공 |
| 최적화기 | **의미 동등성**을 보존하며 IR 연산 최적화 |
| 후단부 | 명령 선택•**레지스터 할당**으로 목적 코드 생성 |

### 쉽게 이해하기 (학습용)
- 전단부와 심볼 테이블이 소스를 검증하고 IR•최적화기•후단부가 기계 코드로 변환한다.

## Ⅳ. 흐름도

```mermaid
sequenceDiagram
    participant C as 컴파일 제어기
    participant FE as 전단부
    participant ST as 심볼 테이블
    participant OPT as 최적화기
    participant BE as 후단부
    C->>FE: 1. 토큰•AST 생성
    FE->>ST: 2. 심볼 정보 조회•갱신
    ST-->>FE: 타입•범위•주소 정보
    FE->>C: 3. 의미 검증•IR 생성
    C->>OPT: 중간 표현
    OPT->>C: 4. IR 최적화
    C->>BE: 최적화 중간 표현
    BE-->>C: 5. 목적 코드 생성
```

**동작 원리**

- **1. 토큰•AST 생성**: 어휘•구문 구조 생성
- **2. 심볼 정보 조회•갱신**: 타입•범위•주소 관리
- **3. 의미 검증•IR 생성**: 검증 AST의 IR 변환
- **4. IR 최적화**: 의미 보존 기반 연산 축소
- **5. 목적 코드 생성**: 명령 선택•레지스터 할당

### 쉽게 이해하기 (학습용)
- 전단부가 소스를 검증해 IR로 바꾸고 최적화기가 의미를 보존하며 개선한 뒤 후단부가 타깃 명령과 레지스터로 변환한다.

## Ⅴ. 종류 및 비교

| 실행 방식 | 컴파일러 | 인터프리터 | JIT 컴파일러 |
|:---|:---|:---|:---|
| 적용 기준 | 반복 실행할 **고정 바이너리**가 필요한 경우 | 대화형 실행과 **즉시 수정** 반영이 필요한 경우 | 장시간 실행 중 **핫 코드** 최적화가 필요한 경우 |
| 핵심 특징 | 실행 전 **전체 번역**으로 목적 코드 산출 | 구문 단위 **즉시 해석** 실행 | 실행 중 **핫 코드**만 기계어 번역 |
| 한계 | 타깃별 **재빌드** 비용 | 반복 해석에 따른 **실행 속도** 저하 | **웜업 구간** 지연•메모리 증가 |

> 요약: 번역 비용을 **빌드 시점**에 둘지 **실행 시점**에 둘지 선택

### 쉽게 이해하기 (학습용)
- 컴파일러는 실행 전에 전체 번역하고, 인터프리터는 구문 단위로 즉시 실행하며, JIT은 실행 중 핫 코드만 기계어로 재사용한다.

## Ⅵ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 최적화 전후 **실행 결과 불일치** | 변환별 **의미 동등성 테스트**•문제 패스 비활성화 | **오컴파일** 방지 |
| 한 오류 뒤 **진단이 연쇄 폭증** | **동기화 토큰** 기반 오류 복구 | 유효한 **후속 오류 진단** 유지 |
| 타깃별 **코드 품질•정확성 차이** | 후단부 회귀 테스트와 **타깃별 검증** | **이식성•코드 생성 신뢰성** 확보 |
| JIT **초기 응답 지연** | 핫 코드 임계값•**프로파일 캐시** 조정 | **웜업 비용•실행 성능** 균형 |

### 쉽게 이해하기 (학습용)
- 컴파일 파이프라인의 단계별 산출물과 실행 결과를 검증하고 최적화 전후 출력이 달라지면 해당 변환 패스를 비활성화해 오컴파일을 막는다.

## Ⅶ. 결론

- **의미 동등성 검증** 후 후단부•패스 배포

### 쉽게 이해하기 (학습용)
- 새 프로세서는 IR 후단부를 교체하고, 실행 결과를 바꾸는 최적화는 비활성화한다.
