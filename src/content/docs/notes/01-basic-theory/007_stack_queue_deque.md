## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **스택(Stack)**: 한쪽 끝에서 후입선출로 처리하는 선형 자료구조이다.
- **큐(Queue)**: 후단 삽입과 전단 삭제로 선입선출하는 선형 자료구조이다.
- **덱(Double-Ended Queue, Deque)**: 양쪽 끝에서 삽입•삭제하는 선형 자료구조이다.
- **끝점**: 원소 삽입과 삭제가 허용되는 자료구조의 앞이나 뒤 위치이다.

</details>

- 정의/개념: 허용 끝점을 제한해 후입선출•선입선출•양단 순서를 구현하는 **스택•큐•덱 자료구조**이다.
- 배경/필요성: 함수 호출 복귀나 작업 대기열 처리 시 목적에 맞지 않는 접근 규칙을 적용하면 순서 역전이나 연산 지연이 발생한다.

#### 한줄 요약

- 허용되는 데이터 끝점 제약을 통해 후입선출(LIFO), 선입선출(FIFO), 양단 접근 메커니즘을 보장한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **후입선출(Last-In First-Out, LIFO)**: 마지막에 삽입한 원소를 가장 먼저 제거하는 처리 규칙이다.
- **선입선출(First-In First-Out, FIFO)**: 가장 먼저 삽입한 원소를 가장 먼저 제거하는 처리 규칙이다.
- **상수 시간 $O(1)$**: 입력 크기와 무관하게 일정한 횟수로 끝나는 연산 시간이다.
- **오버플로(Overflow)**: 포화 상태에서 삽입을 시도한 오류이다.
- **언더플로(Underflow)**: 공백 상태에서 삭제를 시도한 오류이다.

</details>

- **LIFO•FIFO**•양방향 입출력에 따른 처리 순서를 통제한다.
- 허용 끝점의 **상수 시간** 삽입•삭제가 핵심이다.
- 공백•포화 검사로 **오버플로•언더플로**를 방지한다.

#### 한줄 요약

- 포인터 또는 인덱스 갱신을 통해 데이터 크기(N)와 독립된 $O(1)$의 삽입/삭제 성능을 보장한다.


## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **연산 인터페이스(Operation Interface)**: 내부 저장 방식을 숨기고 허용된 삽입•삭제 연산만 제공하는 접점이다.
- **상단**: 스택에서 삽입•삭제가 일어나는 끝점이다.
- **전단**: 큐•덱의 앞쪽 끝점이다.
- **후단**: 큐•덱의 뒤쪽 끝점이다.
- **저장소**: 배열이나 연결 리스트로 원소를 보관하는 내부 공간이다.

</details>

```text
선형 자료구조 구성
├─ 연산 인터페이스
├─ 끝점 상태
└─ 저장소
```

가지의 의미: 입출력 통제•위치•저장의 정적 책임 분리를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 연산 인터페이스 | **허용 끝점**의 삽입•삭제 통제 |
| 끝점 상태 | **상단•전단•후단** 위치•경계 관리 |
| 저장소 | 배열•연결 리스트에 원소 저장 |

#### 한줄 요약

- 캡슐화된 연산 인터페이스(Push/Pop, Enqueue/Dequeue)가 끝점 상태 및 내부 배열/연결리스트 레포지토리를 제어한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **경계 상태**: 현재 원소 수와 용량으로 판단한 공백•포화 여부이다.
- **끝점 위치 갱신**: 삽입•삭제 뒤 상단•전단•후단 인덱스나 참조를 변경하는 작업이다.
- **경계 오류**: 공백에서 삭제하거나 포화 상태에서 삽입할 때 반환하는 오류이다.

</details>

```text
입출력 요청
   │
   ▼
1. 경계 상태 판정
├─ 공백•포화: 경계 오류 반환
└─ 연산 가능
   │
   ▼
2. 끝점 원소 변경
   │
   ▼
3. 끝점 위치 갱신
   │
   ▼
처리 결과 반환
```

**동작 원리**

1. **경계 상태 판정**: 저장소의 공백•포화 여부를 확인하여 요청한 연산을 수행할 수 있는지 판단한다.
2. **끝점 원소 변경**: 자료구조가 허용하는 상단•전단•후단 위치에서 원소를 삽입하거나 삭제한다.
3. **끝점 위치 갱신**: 원소 변경이 끝난 뒤 상단•전단•후단 인덱스와 원소 수를 일관되게 갱신한다.

#### 한줄 요약

- 인터페이스는 허용된 끝점의 원소와 위치를 함께 갱신한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **선두 차단(Head-of-Line Blocking)**: 큐의 첫 작업이 지연되어 뒤의 처리 가능한 작업까지 대기하는 현상이다.
- **스택 오버플로(Stack Overflow)**: 호출이나 원소가 허용 깊이를 넘어 스택 저장 공간이 소진된 상태이다.
- **호출 이력**: 함수 호출과 복귀 순서를 후입선출로 보관한 실행을 기록한다.
- **접근 규칙**: 삽입•삭제를 허용할 끝점을 제한해 원소 처리 순서를 결정하는 규칙이다.

</details>

| 선형 자료구조 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 적용 기준 | **호출 이력**•되돌리기 관리 | 도착 순서의 **큐** 처리 | **양단 삽입•삭제** 필요 |
| 핵심 특징 | **후입선출**로 최근 원소부터 처리 | **선입선출**로 도착 원소부터 처리 | **양단** 중 선택해 처리 |
| 한계 | 깊이 증가 시 **스택 오버플로** | **선두 차단**으로 후속 작업 지연 | 양단 **접근 규칙** 혼용 시 순서 오류 |

> 요약: 역순은 **스택**, 도착순은 **큐**, 양단 처리는 덱이 핵심이다.

#### 한줄 요약

- 역순 되돌리기(Undo/Call Stack)는 스택, 순차 처리(Buffer/Queue)는 큐, 양방향 입출력은 덱(Deque)을 선정한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **원형 큐(Circular Queue)**: 배열 끝과 시작을 이어 비운 슬롯을 재사용하는 큐이다.
- **원자적 인덱스 갱신(Atomic Index Update)**: 동시 실행 중에도 끝점 인덱스 변경이 나뉘지 않은 한 연산처럼 완료되는 방식이다.
- **연산 선형성**: 동시 연산이 한 시점에 순서대로 실행된 것처럼 관찰되는 성질이다.
- **잠금(Lock)**: 여러 실행 흐름이 같은 끝점 상태를 동시에 변경하지 못하도록 접근을 직렬화하는 수단이다.
- **조기 포화**: 배열 큐의 앞쪽 빈 슬롯이 남았는데 후단이 배열 끝에 도달해 삽입할 수 없다고 판단하는 상태이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **공백•포화 상태** 미검사로 경계 밖 삭제•삽입 | 연산 전 원소 수•용량 검사 | 언더플로•오버플로의 **경계 오류 방지** |
| 배열 큐가 삭제 슬롯을 재사용하지 못해 **조기 포화** | **원형 큐** 인덱스 순환 적용 | 고정 배열의 빈 슬롯 재사용 |
| 동시 **끝점 위치 갱신** 경쟁으로 원소 유실•순서 역전 | **잠금** 또는 **원자적 인덱스 갱신** 적용 | 원소 순서와 **연산 선형성** 보장 |
| 잘못된 끝점 사용으로 **LIFO•FIFO** 정책 위반 | 자료구조별 **연산 인터페이스** 제한 | 자료구조의 접근 규칙 준수 |

#### 한줄 요약

- 바운더리 체크(Underflow/Overflow)와 동시성 제어(Atomic/Lock)를 수행하고 원형 인덱싱(Circular Indexing)으로 메모리 재사용성을 확보한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **선택 기준**: 업무가 요구하는 제거 순서와 허용 끝점에 따라 자료구조를 고르는 판단 기준이다.

</details>

- **선택 기준**이 최근 항목 우선이면 스택, 도착순이면 큐, 양단 처리면 덱을 선택한다.

#### 한줄 요약

- 처리 순서가 역순•도착순•양단인지에 따라 스택•큐•덱을 선택한다.
