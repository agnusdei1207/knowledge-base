## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **스택(Stack)**: 한쪽 끝에서 후입선출로 처리하는 선형 자료구조
- **큐(Queue)**: 후단 삽입과 전단 삭제로 선입선출하는 선형 자료구조
- **덱(Double-Ended Queue, Deque)**: 양쪽 끝에서 삽입•삭제하는 선형 자료구조
- **끝점**: 원소 삽입과 삭제가 허용되는 자료구조의 앞이나 뒤 위치

</details>

- 정의/개념: 입출력 **끝점**으로 순서를 통제하는 선형 자료구조
- 배경/필요성: 임의 위치 입출력은 **처리 순서 일관성** 보장 곤란

#### 한줄 요약

- 접시 더미•대기 줄•양쪽 문처럼 접근 끝점이 처리 순서를 정한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **후입선출(Last-In First-Out, LIFO)**: 마지막에 삽입한 원소를 가장 먼저 제거하는 처리 규칙
- **선입선출(First-In First-Out, FIFO)**: 가장 먼저 삽입한 원소를 가장 먼저 제거하는 처리 규칙
- **상수 시간 $O(1)$**: 입력 크기와 무관하게 일정한 횟수로 끝나는 연산 시간
- **오버플로(Overflow)**: 포화 상태에서 삽입을 시도한 오류
- **언더플로(Underflow)**: 공백 상태에서 삭제를 시도한 오류

</details>

- **LIFO•FIFO**•양방향 입출력에 따른 처리 순서 통제
- **끝점 갱신** 기반 $O(1)$ 삽입•삭제
- 공백•포화 검사를 통한 **경계 오류 방지**

#### 한줄 요약

- 접시 더미는 맨 위, 대기 줄은 앞뒤 끝만 움직이듯, 허용된 끝점의 위치만 바꾸면 원소 수와 무관하게 삽입•삭제할 수 있다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **연산 인터페이스(Operation Interface)**: 내부 저장 방식을 숨기고 허용된 삽입•삭제 연산만 제공하는 접점
- **상단**: 스택에서 삽입•삭제가 일어나는 끝점
- **전단**: 큐•덱의 앞쪽 끝점
- **후단**: 큐•덱의 뒤쪽 끝점
- **저장소**: 배열이나 연결 리스트로 원소를 보관하는 내부 공간

</details>

```text
선형 자료구조 구성
├─ 연산 인터페이스
├─ 끝점 상태
└─ 저장소
```

가지의 의미: 입출력 통제•위치•저장의 정적 책임 분리

| 구성요소 | 책임 |
|:---|:---|
| 연산 인터페이스 | **허용 끝점**의 삽입•삭제 통제 |
| 끝점 상태 | **상단•전단•후단** 위치•경계 관리 |
| 저장소 | 배열•연결 리스트에 원소 저장 |

#### 한줄 요약

- 연산 인터페이스가 사용할 끝점을 제한하고, 끝점 상태와 저장소가 원소의 위치와 값을 함께 관리한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **경계 상태**: 현재 원소 수와 용량으로 판단한 공백•포화 여부
- **끝점 위치 갱신**: 삽입•삭제 뒤 상단•전단•후단 인덱스나 참조를 변경하는 작업
- **경계 오류**: 공백에서 삭제하거나 포화 상태에서 삽입할 때 반환하는 오류

</details>

```text
입출력 요청
   │
   ▼
1. 경계 상태 판정
├─ 공백•포화: 경계 오류 반환
└─ 연산 가능
   │
   ▼
2. 끝점 원소 변경
   │
   ▼
3. 끝점 위치 갱신
   │
   ▼
처리 결과 반환
```

**동작 원리**

1. **경계 상태 판정**: 공백•포화 여부로 연산 가능성 확인
2. **끝점 원소 변경**: 허용된 위치의 원소 삽입•삭제
3. **끝점 위치 갱신**: 처리 후 상단•전단•후단 반영

#### 한줄 요약

- 인터페이스는 허용된 끝점의 원소와 위치를 함께 갱신한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **선두 차단(Head-of-Line Blocking)**: 큐의 첫 작업이 지연되어 뒤의 처리 가능한 작업까지 대기하는 현상
- **스택 오버플로(Stack Overflow)**: 호출이나 원소가 허용 깊이를 넘어 스택 저장 공간이 소진된 상태
- **호출 이력**: 함수 호출과 복귀 순서를 후입선출로 보관한 실행 기록

</details>

| 선형 자료구조 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 적용 기준 | **호출 이력**•되돌리기 관리 | 도착 순서대로 **작업 처리** | **양단 삽입•삭제** 필요 |
| 핵심 특징 | **후입선출**로 최근 원소부터 처리 | **선입선출**로 도착 원소부터 처리 | **양단** 중 선택해 처리 |
| 한계 | 깊이 증가 시 **스택 오버플로** | **선두 차단**으로 후속 작업 지연 | 양단 규칙 혼용 시 **순서 오류** |

> 요약: 역순은 **스택**, 도착순은 **큐**, 양단 처리는 덱

#### 한줄 요약

- 쌓은 접시를 거꾸로 꺼내면 스택, 매표소 도착순으로 보내면 큐, 통로 양쪽 문을 모두 쓰면 덱이다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **원형 큐(Circular Queue)**: 배열 끝과 시작을 이어 비운 슬롯을 재사용하는 큐
- **원자적 인덱스 갱신(Atomic Index Update)**: 동시 실행 중에도 끝점 인덱스 변경이 나뉘지 않은 한 연산처럼 완료되는 방식
- **연산 선형성**: 동시 연산이 실제로는 한 시점에 순서대로 실행된 것처럼 관찰되는 성질
- **잠금(Lock)**: 여러 실행 흐름이 같은 끝점 상태를 동시에 변경하지 못하도록 접근을 직렬화하는 수단

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| **공백•포화 상태** 미검사로 경계 밖 삭제•삽입 | 연산 전 원소 수•용량 검사 | 언더플로•오버플로의 **경계 오류 방지** |
| 배열 큐가 삭제 슬롯을 재사용하지 못해 **조기 포화** | **원형 큐** 인덱스 순환 적용 | 고정 배열의 **전체 용량 재사용** |
| 동시 **끝점 갱신** 경쟁으로 원소 유실•순서 역전 | 잠금 또는 원자적 인덱스 갱신 | 원소 순서와 **연산 선형성** 보장 |
| 잘못된 끝점 사용으로 **LIFO•FIFO 정책 위반** | 자료구조별 허용 연산 인터페이스 제한 | 자료구조의 **처리 순서 일관성** 확보 |

#### 한줄 요약

- 창고 출입구를 하나씩 통제하듯 빈 공간•용량•동시 접근을 확인하고 허용된 끝점만 갱신한다.

## Ⅶ. 결론

- 최근 항목 우선은 **스택**, 도착순은 큐, 양단 처리는 덱 선택

#### 한줄 요약

- 처리 순서가 역순•도착순•양단인지에 따라 스택•큐•덱을 선택한다.
