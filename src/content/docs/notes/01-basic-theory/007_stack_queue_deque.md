## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **스택(Stack)**: 단일 상단(Top) 끝점에서 삽입과 삭제가 이루어지는 후입선출(LIFO) 선형 자료구조.
- **큐(Queue)**: 후단(Rear) 삽입과 전단(Front) 삭제로 데이터를 처리하는 선입선출(FIFO) 선형 자료구조.
- **덱(Deque, Double-Ended Queue)**: 전단과 후단 양쪽 끝점 모두에서 삽입과 삭제가 가능한 선형 자료구조.
- **끝점(Endpoint)**: 원소 삽입과 삭제가 허용되는 자료구조의 전단, 후단, 상단 인터페이스 위치.

</details>

- 정의/개념: 허용 **끝점**을 제한하여 후입선출(LIFO)의 **스택**, 선입선출(FIFO)의 **큐**, 양단(Both-Ends)의 **덱** 처리 규칙을 구현하는 선형 자료구조 체계
- 배경/필요성: 데이터의 임의 위치 접근을 허용할 경우 처리 순서 역전과 동기화 무결성 훼손이 발생하는 데이터 흐름 제어의 불확실성 한계

#### 한줄 요약

- 접근 가능한 위치를 일부러 좁혀 임의 접근을 포기하는 대신 순서 규칙 위반 자체를 구조적으로 불가능하게 만든다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **LIFO(Last-In First-Out, 후입선출)**: 가장 마지막에 삽입된 데이터가 가장 먼저 인출되는 처리 규칙.
- **FIFO(First-In First-Out, 선입선출)**: 가장 먼저 삽입된 데이터가 가장 먼저 인출되는 처리 규칙.
- **오버플로(Overflow)**: 용량이 가득 찬 포화 상태에서 추가 삽입을 시도할 때 발생하는 경계 오류.
- **언더플로(Underflow)**: 데이터가 없는 공백 상태에서 삭제를 시도할 때 발생하는 경계 오류.

</details>

- **LIFO**·**FIFO**·양방향 입출력 규칙에 따른 엄격한 데이터 흐름 제어
- 포인터/인덱스 갱신을 통해 데이터 크기($n$)와 무관하게 보장되는 상수 시간 $O(1)$ 삽입·삭제
- 사전 용량 및 공백 상태 검사를 통한 **오버플로** 및 **언더플로** 경계 오류 원천 차단

#### 한줄 요약

- 포인터나 인덱스만 갱신하여 $O(1)$ 삽입·삭제를 보장한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **연산 인터페이스(Operation Interface)**: 내부 구현을 은닉하고 push, pop, enqueue, dequeue 등 허용된 끝점 연산만 외부에 제공하는 접점.
- **끝점 상태(Endpoint State)**: 상단(Top), 전단(Front), 후단(Rear) 포인터 및 인덱스 위치.
- **저장소(Underlying Storage)**: 연속 배열 또는 비연속 연결 리스트로 원소를 보관하는 내부 메모리 공간.

</details>

```text
+-------------------------------------------------------------+
|             Linear Restricted-Access ADT Architectures      |
|  +-------------------------------------------------------+  |
|  | Stack (LIFO): Single-End Push / Pop (Top Pointer)     |  |
|  | [Element N] <- Top | [Element N-1] | ... | [Bottom]   |  |
|  +-------------------------------------------------------+  |
|  +-------------------------------------------------------+  |
|  | Queue (FIFO): Dual-End Enqueue(Rear) / Dequeue(Front) |  |
|  | Out <- [Front] | [Data 1] | ... | [Rear] <- In        |  |
|  +-------------------------------------------------------+  |
|  +-------------------------------------------------------+  |
|  | Deque (Double-Ended): Push/Pop Front & Push/Pop Rear  |  |
|  | In/Out <-> [Front] | ... | [Rear] <-> In/Out          |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

선의 의미: 실선 박스는 추상 자료형별 끝점 인터페이스 경계를 나타내며 화살표는 각 자료구조가 강제하는 데이터 입출력 방향과 인덱스 포인터 제어 흐름을 나타냄

| 구성요소 | 책임 |
|:---|:---|
| **연산 인터페이스** | 허용 **끝점** 삽입•삭제 연산 통제 |
| **끝점 상태** | 상단•전단•후단 인덱스 및 경계 관리 |
| **저장소** | 고정 배열 또는 연결 리스트 기반 원소 보관 |

#### 한줄 요약

- 연산 인터페이스가 허용 끝점과 저장소의 원소를 함께 관리한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **경계 상태 판정**: 현재 원소 수와 전체 용량을 비교하여 공백(Empty) 또는 포화(Full) 상태를 확인하는 과정.
- **끝점 위치 갱신**: 삽입/삭제 완료 후 Top, Front, Rear 인덱스나 포인터를 원자적으로 이동하는 단계.

</details>

```text
[자료구조 입출력 연산 요청 (Push/Pop/Enqueue/Dequeue)]
                        │
                        ▼
             <저장소 경계 상태 검사>
                        │
             ┌──────────┴──────────┐
             │                     │
    [용량 초과 / 고갈]         [정상 범위]
             │                     │
             ▼                     ▼
[언더플로 / 오버플로 오류]  [1. 허용 끝점 포인터 위치 확인]
                                   │
                                   ▼
                            [2. 데이터 쓰기 / 읽기 수행]
                                   │
                                   ▼
                            [3. 원자적 끝점 인덱스 포인터 갱신]
                                   │
                                   ▼
                            [4. 연산 완료 및 결과 반환]
```

분기 결과: 공백 시 Pop이나 포화 시 Push 요청은 언더플로/오버플로 오류를 반환하여 데이터 무결성을 보호하며, 정상 범위 요청은 $O(1)$의 단일 포인터 조작으로 완료됨

**동작 원리**:
1. 연산 진입 시 저장소의 현재 원소 수와 최대 할당 크기를 비교하여 언더플로(공백) 또는 오버플로(포화) 경계 상태를 선제 검증함.
2. 검증 통과 시 스택(Top), 큐(Front/Rear), 덱(양단) 중 호출된 **연산 인터페이스**가 지정하는 고유 **끝점 상태** 주소를 식별함.
3. 대상 끝점 위치에 신규 데이터를 기록(Push/Enqueue)하거나 기존 원소를 버퍼로 복사 추출(Pop/Dequeue)함.
4. 연산 성공 직후 모듈러 연산이나 포인터 대입을 통해 끝점 인덱스를 갱신하고 내부 원소 카운터를 원자적으로 증감시킴.
5. 갱신된 끝점 상태의 일관성을 확정한 후 호출자에게 처리 성공 플래그 또는 추출된 데이터를 즉시 반환함.

#### 한줄 요약

- 경계 판정과 끝점 갱신을 한 연산 안에 묶어야 중간에 끼어든 요청이 순서 규칙을 깨지 못한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **호출 이력(Call Stack)**: 함수 호출 시 복귀 주소와 지역 변수를 후입선출 방식으로 보관하는 실행 스택 프레임.
- **선두 차단(Head-of-Line Blocking, HoL Blocking)**: 큐의 선두 작업이 지연되어 뒤의 처리 가능한 후속 작업들까지 대기하는 병목 현상.
- **스택 오버플로(Stack Overflow)**: 재귀 호출이나 원소 적재가 허용 메모리 한계를 초과하여 발생하는 시스템 장애.

</details>

| 자료구조 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| 적용 기준 | 함수 **호출 이력**, 실행 취소(Undo) 및 괄호 문법 검증 시 | 비동기 작업 대기열, 인쇄 스풀링 및 패킷 버퍼링 순차 처리 시 | 슬라이딩 윈도우 최대값 추출 및 양방향 스케줄링 큐 구현 시 |
| 핵심 특징 | **후입선출** 최근 데이터 우선 | **선입선출** 도착 순서 처리 | 양단 자유 삽입/삭제 |
| 한계 | 과도한 재귀 시 **스택 오버플로** | 선두 지연 시 **선두 차단** 병목 | 양단 접근 규칙 혼용 시 순서 무결성 저하 |

#### 한줄 요약

- 역순 복원은 스택, 순차 버퍼링은 큐, 양단 입출력은 덱을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **원형 큐(Circular Queue)**: 배열의 끝과 시작을 모듈러 연산으로 이어 선형 큐의 메모리 낭비(조기 포화)를 해결한 큐.
- **뮤텍스(Mutual Exclusion, Mutex)**: 다중 스레드 환경에서 임계 구역의 동시 접근을 제어하는 상호 배제 잠금.
- **원자적 인덱스 갱신(Atomic Index Update)**: 멀티스레드 환경에서 비교 및 교환(CAS) 연산으로 끝점 인덱스를 락프리로 갱신하는 동기화 기법.
- **연산 선형성(Linearizability)**: 모든 동시성 연산이 어느 한 시점에 원자적으로 실행된 것처럼 관측되는 일관성 보장 성질.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 공백•포화 상태 미검사로 경계 밖 삭제•삽입 | 연산 전 원소 수•용량 검사 | **언더플로**•**오버플로** 경계 오류 방지 |
| 배열 큐가 삭제 슬롯을 재사용하지 못해 조기 포화 | **원형 큐** 인덱스 순환 적용 | 고정 배열의 빈 슬롯 재사용 |
| 동시 **끝점 위치 갱신** 경쟁으로 원소 유실•순서 역전 | **뮤텍스** 잠금 또는 **원자적 인덱스 갱신** 적용 | 원소 순서와 **연산 선형성** 보장 |
| 잘못된 끝점 사용으로 **LIFO**•**FIFO** 정책 위반 | 자료구조별 **연산 인터페이스** 제한 | 자료구조의 접근 규칙 준수 |

#### 한줄 요약

- 삽입·삭제 전에 경계 검사를 수행하고, 배열 큐는 원형 인덱싱으로 슬롯을 재사용하며, 동시 접근 시에는 원자적 CAS로 끝점 갱신을 보호해야 한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **접근 정책(Access Policy)**: 스택의 LIFO, 큐의 FIFO, 덱의 양단 접근처럼 자료구조가 원소 입출력 순서를 제한하는 규칙.

</details>

- OS 인터럽트/함수 호출 스택(LIFO), 비동기 메시지 큐/네트워크 I/O 버퍼(FIFO) 및 슬라이딩 윈도우(Deque)의 **접근 정책**을 제공하는 핵심 선형 추상 자료형(ADT)으로 확립되었으며, 고성능 멀티스레드 환경에서는 원형 큐(Circular Queue) 및 락프리 동기화(LMAX Disruptor 링버퍼, CAS 기반 논블로킹 큐) 아키텍처로 고도화되고 있어, 시스템 설계자는 동시성 경합 수준과 입출력 순서 제약 조건에 따라 적합한 ADT와 락프리 메모리 구조를 선택해야 한다.

#### 한줄 요약

- 가장 최근에 넣은 것을 먼저 꺼내야 하면 스택, 먼저 넣은 것을 먼저 꺼내야 하면 큐, 양쪽 모두 필요하면 덱을 선택한다.
