## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **최단 경로(Shortest Path)**: 가중치 그래프의 두 정점 사이를 잇는 경로 중 간선 가중치(거리, 비용, 지연시간)의 총합이 최소가 되는 경로.
- **가중치(Weight)**: 간선에 부여된 물리적 거리, 네트워크 지연, 통행 비용 등의 수치적 비용 값.
- **최단 거리 테이블(Distance Array)**: 출발점으로부터 각 정점까지의 현재까지 발견된 최소 비용 후보 값을 보관하는 배열.

</details>

- 정의/개념: 간선 가중치 합이 최소인 경로를 탐색하는 알고리즘 체계
- 배경/필요성: 가중치 그래프에서 단순 홉 기반 BFS 적용 시 비용 최소 경로와 불일치하고 전수 경로 탐색 시 조합 폭증($O(V!)$)이 발생하는 경로 탐색 복잡도 한계

#### 한줄 요약

- 가중치를 도입하는 순간 홉 최소와 비용 최소가 갈라지므로, 무엇을 비용으로 볼지 정하는 일이 알고리즘 선택보다 앞선다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **최적 부분 구조(Optimal Substructure)**: 전체 최단 경로를 구성하는 임의의 부분 경로 역시 해당 구간의 최단 경로가 되는 수학적 성질.
- **완화(Relaxation)**: $d(v) > d(u) + w(u, v)$일 때 $d(v) = d(u) + w(u, v)$로 갱신하여 최단 거리를 점진적으로 단축하는 삼각부등식 연산.
- **수렴(Convergence)**: 완화 연산을 반복하여 더 이상 최단 거리 배열의 값이 갱신되지 않고 최적해가 확정된 상태.
- **단일 출발점 최단 경로(Single-Source Shortest Path, SSSP)**: 하나의 시작 정점으로부터 그래프 내 다른 모든 정점까지의 최단 경로를 구하는 문제.
- **모든 쌍 최단 경로(All-Pairs Shortest Path, APSP)**: 그래프 내의 모든 정점 쌍 간의 최단 경로를 구하는 문제.

</details>

- 전체 최단 경로가 구간별 최단 경로로 구성되는 **최적 부분 구조**
- **완화** 반복으로 거리 후보를 줄여 최단 거리로 **수렴**
- 가중치 부호와 **SSSP·APSP** 범위에 따른 알고리즘 분기

#### 한줄 요약

- 최적 부분 구조 전제 하에 완화 연산 $d(v) = \min(d(v), d(u) + w(u,v))$을 수렴 시까지 반복한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **선행 정점(Predecessor Vertex, $\pi[v]$)**: 최단 경로에서 정점 $v$ 직전에 위치한 정점으로 목적지에서 출발지로 역추적(Backtracking)하여 경로 복원에 사용.
- **우선순위 큐(Min-Heap Priority Queue)**: 다익스트라에서 미방문 정점 중 최단 거리 후보를 $O(\log V)$ 시간에 즉시 인출하기 위한 힙 자료구조.

</details>

```text
[최단 경로 연산 체계]
  │
  ├─ [가중치 그래프] (정점 V·간선 E·가중치 W 모델)
  │
  ├─ [완화 연산 제어기]
  │     ├─ [간선 완화기] (d(v) > d(u) + w(u,v) 판정)
  │     └─ [우선순위 큐] (Min-Heap 기반 최소 거리 인출)
  │
  └─ [상태 저장소]
        ├─ [거리 배열 Dist[V]] (정점별 최단 거리 테이블)
        └─ [선행 정점 배열 Pi[V]] (경로 역추적 테이블)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 가중치 그래프 | 정점•간선•**가중치** 보관 |
| 최단 거리 배열 | 정점별 **최소 비용 후보** 누적 |
| **선행 정점** 배열 | **경로 역추적**용 직전 정점 보관 |
| 완화 연산기 | **완화 규칙**으로 거리·선행 정점 갱신 |

#### 한줄 요약

- 간선 가중치를 기반으로 완화 연산을 수행하고, 갱신 시 최단 거리 테이블과 선행 정점을 갱신한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **음수 사이클(Negative Cycle)**: 사이클을 1회 순환할 때마다 가중치 합이 음수가 되어 최단 거리가 무한히 감소하는 순환.

</details>

```text
[최단 경로 계산 요청 (출발 정점 S)]
                 │
                 ▼
         <탐색 대상 범위 판정>
                 │
  ┌──────────────┴──────────────┐
  │                             │
[단일 출발점 (SSSP)]     [모든 정점 쌍 (APSP)]
  │                             │
  ▼                             ▼
<음수 가중치 간선 유무>     <플로이드-워셜 3중 루프 실행>
  │
  ├─────────────────────────────┐
  │                             │
[음수 간선 없음]            [음수 간선 존재]
  │                             │
  ▼                             ▼
[다익스트라: Min-Heap 완화]  [벨만-포드: V-1회 전간선 완화]
  │                             │
  │                             ▼
  │                      <V번째 추가 완화 성공 여부>
  │                             │
  │                    ┌────────┴────────┐
  │                    │                 │
  │                [추가 완화 성공]  [추가 완화 없음]
  │                    │                 │
  │                    ▼                 ▼
  │             [음수 사이클 검출]  [최단 거리 확정]
  ▼                    │                 │
[최단 거리 d[v] 및 경로 확정] <──────────┘
```

분기 결과: 음수 간선이 없는 환경에서는 다익스트라가 매 단계 최소 정점을 확정하여 $O((V+E)\log V)$로 수렴하며, 음수 간선이 존재하면 벨만-포드가 $V-1$회 완화 후 $V$회차 추가 갱신 여부로 음수 사이클을 판정함

**동작 원리**:
1. 출발 정점의 거리를 0으로, 타 정점 거리를 무한대($\infty$)로 초기화하고 **선행 정점** 포인터를 널로 설정함.
2. 다익스트라는 **우선순위 큐**(Min-Heap)에서 최단 거리 후보 정점 $U$를 추출하고 방문 확정 상태로 전이함.
3. 정점 $U$와 인접한 모든 간선 $(U, V)$에 대해 $d[V] > d[U] + w(U,V)$ 조건을 검사하는 **완화 규칙** 연산을 수행함.
4. 완화 조건 충족 시 $d[V]$를 단축된 거리로 갱신하고 선행 정점 배열에 $U$를 기록하여 경로 역추적 토대를 갱신함.
5. 벨만-포드는 전체 간선 $E$에 대해 $V-1$회 완화를 반복한 뒤, $V$회차 순회에서 거리 단축이 발생하면 **음수 사이클**로 즉시 판정함.

#### 한줄 요약

- 음수 간선의 유무가 확정을 되돌릴 수 있는지를 결정하고, 그 되돌림 비용이 곧 알고리즘 간 차수 차이로 나타난다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **다익스트라(Dijkstra)**: 비음수 가중치에서 우선순위 큐를 이용해 매 단계 최소 거리 정점을 확정하는 탐욕 알고리즘.
- **벨만-포드(Bellman-Ford)**: 모든 간선을 $V-1$회 반복 완화하여 음수 가중치 및 음수 사이클을 판정하는 동적 계획법 알고리즘.
- **플로이드-워셜(Floyd-Warshall)**: 3중 루프로 경유 정점 $k$를 1부터 $V$까지 확장하며 모든 쌍 최단 거리를 구하는 알고리즘.

</details>

| 최단 경로 알고리즘 | 다익스트라 | 벨만-포드 | 플로이드-워셜 |
|:---|:---|:---|:---|
| 적용 기준 | 비음수 가중치 도로망 및 네트워크 **SSSP** 탐색 시 | 음수 가중치 허용 및 **음수 사이클** 검출 요구 시 | 노드 수 제한적 밀집 그래프의 모든 정점 쌍 **APSP** 산출 시 |
| 핵심 특징 | **최소 힙** 기반 최소 거리 정점 탐욕적 확정 | 전체 간선 $E$를 $V-1$회 반복 완화 | 3중 루프 기반 **경유 정점 $k$** 점진 확장 |
| 한계 | 음수 간선에서 **최단 거리 오산** | $O(VE)$ 시간으로 **처리 지연** | $O(V^3)$ 시간·$O(V^2)$ 공간 |

#### 한줄 요약

- 비음수 단일 출발은 다익스트라, 음수 간선은 벨만-포드, 모든 쌍 밀집 그래프는 플로이드-워셜을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **무한대 오버플로(INF Overflow)**: 도달 불가 상태를 나타내는 `INF` 값에 간선 가중치를 더할 때 정수 오버플로로 음수가 되는 현상.
- **조기 종료 조건(Early Stopping)**: 목표 정점이 우선순위 큐에서 추출되는 즉시 탐색을 멈추어 불필요한 잔여 그래프 순회를 차단하는 기법.
- **SPFA(Shortest Path Faster Algorithm)**: 벨만-포드에서 거리가 갱신된 정점만 큐에 넣어 완화 횟수를 평균 $O(E)$로 최적화한 알고리즘.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| `INF + w` 덧셈 시 **정수 오버플로**로 음수 왜곡 | 포화 연산(Saturation) 또는 안전 상수 사용 | 비정상 단축 및 오버플로 방지 |
| 단일 목적지 탐색에서 전역 완료 대기로 지연 | 목표 노드 인출 시 **조기 종료** 적용 | 불필요한 잔여 노드 완화 생략 |
| 벨만-포드의 $O(VE)$ 고정 반복으로 성능 저하 | 큐 기반 완화 알고리즘(**SPFA**) 적용 | 평균 시간복잡도 $O(E)$ 수준 단축 |
| 음수 사이클 존재 시 무한 루프 및 경로 왜곡 | $V$번째 반복 시 거리 갱신 검출 | **음수 사이클** 조기 식별 및 차단 |

#### 한줄 요약

- 실무에서는 오버플로 안전 상수를 적용하고, 단일 목표는 조기 종료로 가속하며, 음수 간선은 SPFA와 V회차 검증으로 제어한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **가중치 조건(Weight Condition)**: 간선 가중치의 부호(비음수/음수)와 계산 대상 범위(단일 출발점 SSSP/전 쌍 APSP)에 따라 최적 알고리즘을 결정하는 평가 기준.
- **최단 경로 우선 프로토콜(Open Shortest Path First, OSPF)**: 링크 상태 정보를 공유하고 다익스트라 알고리즘을 수행하여 최단 전달 경로를 산출하는 내부 관문 라우팅 프로토콜.
- **경계 경로 프로토콜(Border Gateway Protocol, BGP)**: 자율 시스템(Autonomous System) 간에 경로 벡터 정보를 교환하여 글로벌 인터넷 트래픽을 중계하는 표준 라우팅 프로토콜.
- **계층적 축약(Contraction Hierarchies, CH)**: 도로망 그래프에서 중요도가 낮은 정점을 순차적으로 사전 축약하여 수백만 노드의 최단 경로 질의를 수 밀리초 내에 응답하는 가속 기법.

</details>

- 최단 경로 알고리즘은 **OSPF** 및 **BGP** 라우팅의 성숙 표준으로 안착되었으며, 대규모 도로망 및 백본 환경에서는 양방향 탐색과 **계층적 축약(CH)**을 결합한 초저지연 아키텍처로 진화 추세.
- 음수 가중치 및 순환 여부, 그래프 정적·동적 변동 빈도를 분석하여 전처리 시간과 실시간 질의 응답 지연 간 최적 균형점을 도출하는 엔지니어링 결단 필요.

#### 한줄 요약

- 계층적 축약과 사전 전처리 기법으로 진화하는 최단 경로 생태계에서 가중치 조건과 토폴로지 규모에 부합하는 라우팅 엔진 구축 필요.
