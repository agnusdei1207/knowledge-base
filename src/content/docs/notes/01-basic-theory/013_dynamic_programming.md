## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **동적 계획법(Dynamic Programming, DP)**: 중복되는 부분 문제의 해를 저장•재사용해 계산량을 줄이는 알고리즘 설계 기법이다.
- **상태값(State Value)**: 부분 문제를 나타내는 각 상태에서 구할 결과이다.
- **점화식(Recurrence Relation)**: 하위 상태값을 결합해 현재 상태값을 계산하는 식이다.
- **완전 탐색(Exhaustive Search)**: 가능한 후보를 모두 생성•검사해 해를 찾는 방식이다.

</details>

- 정의/개념: 중복 부분 문제의 상태값을 한 번 저장해 점화식에서 재사용하는 **동적 계획법** 설계 기법이다.
- 배경/필요성: 같은 상태에 여러 경로로 도달하는 완전 탐색은 동일한 부분 문제를 반복 계산하여 실행 시간이 급증한다.

#### 한줄 요약

- 큰 퍼즐의 같은 조각을 다시 만날 때 답 쪽지를 꺼내듯, 부분 문제의 상태값을 저장해 중복 계산을 없앤다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **중복 부분 문제(Overlapping Subproblems)**: 같은 작은 문제가 여러 계산 경로에서 반복해 나타나는 성질이다.
- **최적 부분 구조(Optimal Substructure)**: 부분 문제의 최적해로 전체 최적해를 구성할 수 있는 성질이다.
- **기저 상태(Base State)**: 점화식 없이 값이 직접 정해지는 시작 상태이다.
- **계산 순서**: 각 상태보다 의존 상태를 먼저 확정하도록 정한 처리 순서이다.

</details>

- **중복 부분 문제**를 상태로 통합해 상태당 1회를 계산한다.
- 최적화 문제는 **최적 부분 구조**로 **점화식**을 구성한다.
- 기저 상태부터 의존 관계를 따르는 **계산 순서**를 관리한다.

#### 한줄 요약

- 같은 퍼즐 조각은 한 번만 풀고, 작은 조각의 최적 답을 조립 규칙인 점화식으로 합쳐 전체 답을 만든다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **상태(State)**: 부분 문제를 서로 구분하는 최소 변수의 조합이다.
- **메모이제이션(Memoization)**: 필요한 상태를 재귀로 계산해 저장하고 중복 호출 때 재사용하는 방식이다.
- **타뷸레이션(Tabulation)**: 기저 상태부터 의존 순서대로 표를 채워 목표값을 구하는 방식이다.

</details>

```text
동적 계획법 구조
├─ 상태 계산기
└─ 상태 저장소
```

가지의 의미: 상태 계산과 상태값 보관의 정적 책임 분리를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 상태 계산기 | 하위 상태 분해•**점화식** 결합 |
| 상태 저장소 | **메모이제이션•타뷸레이션** 상태값 보관 |

#### 한줄 요약

- 상태 계산기가 점화식으로 필요한 하위 상태를 찾고, 이미 계산한 값은 상태 저장소에서 재사용한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **미계산 상태**: 상태 저장소에 아직 결과가 기록되지 않은 부분 문제이다.
- **의존 상태**: 현재 상태값을 점화식으로 구하기 전에 값이 필요한 하위 상태이다.
- **상태 저장소**: 계산한 상태값을 키와 함께 보관해 이후 요청에서 재사용하는 공간이다.

</details>

```text
목표 상태
   │
   ▼
1. 상태값 조회
├─ 계산됨: 상태값 반환
└─ 미계산
   │
   ▼
2. 의존 상태 계산
   ├─ 의존 상태 존재: 계산 반복
   └─ 의존 상태 확정
      │
      ▼
3. 점화식 결합
   │
   ▼
4. 현재 상태값 저장
   │
   ▼
상태값 반환
```

**동작 원리**

1. **상태값 조회**: 목표 또는 하위 상태가 이미 계산되었으면 저장된 값을 즉시 재사용한다.
2. **의존 상태 계산**: 값이 없으면 기저 조건을 적용하거나 점화식이 참조하는 더 작은 상태를 계산한다.
3. **점화식 결합**: 의존 상태의 값들을 점화식에 대입하여 현재 상태의 값을 구한다.
4. **현재 상태값 저장**: 계산한 값을 상태 저장소에 기록하여 이후 같은 상태 요청에서 재사용한다.

#### 한줄 요약

- 계산기가 답안 서랍에서 상태값을 먼저 찾고, 빈칸이면 더 작은 문제를 풀어 점화식으로 합친 뒤 같은 서랍에 기록한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **하향식(Top-down)**: 목표 상태에서 필요한 하위 상태만 재귀로 계산•저장하는 방식이다.
- **상향식(Bottom-up)**: 기저 상태부터 의존 순서대로 전체 상태값을 계산하는 방식이다.
- **희소 상태 공간(Sparse State Space)**: 정의 가능한 상태 중 목표 계산에서 실제 도달하는 상태가 일부뿐인 공간이다.
- **호출 스택(Call Stack)**: 재귀 함수의 반환 위치와 지역 상태를 저장하는 메모리 영역이다.
- **의존 순서**: 현재 상태보다 필요한 하위 상태를 먼저 계산하도록 정한 순서이다.
- **공간복잡도(Space Complexity)**: 입력 크기에 따라 추가 메모리 사용량이 증가하는 정도이다.
- **상태 공간(State Space)**: 문제에서 정의할 수 있는 모든 상태의 집합이다.

</details>

| DP 구현 방식 | 하향식 | 상향식 |
|:---|:---|:---|
| 적용 기준 | 도달 가능 **희소 상태 공간** | 의존 순서가 명확한 전체 **상태 공간** 계산 |
| 핵심 특징 | 목표 의존 상태만 **메모이제이션** | **의존 순서**대로 전체 표 계산 |
| 한계 | 재귀 깊이에 따른 **호출 스택** 초과 | 미사용 상태까지 채워 **공간복잡도** 증가 |

> 요약: **상태 공간** 대비 실제 계산량으로 방식을 선택한다.

#### 한줄 요약

- 필요한 칸이 드문 표는 목표 칸부터 거슬러 채우고, 모든 칸이 필요하면 첫 칸부터 순서대로 채운다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **상태 정의**: 이후 선택 결과를 구분하는 최소 정보를 하나의 부분 문제로 표현하는 기준이다.
- **순환 의존**: 상태들이 서로의 값을 먼저 요구해 계산 순서를 정할 수 없는 관계이다.
- **롤링 배열(Rolling Array)**: 현재 계산에 필요한 최근 상태 범위만 유지해 공간 사용량을 줄이는 기법이다.
- **명시적 스택**: 재귀 호출 대신 프로그램이 직접 미처리 상태를 넣고 꺼내는 저장 구조이다.
- **상태 전이**: 현재 상태와 선택에서 다음 상태로 이동하는 관계이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 불완전한 **상태 정의**로 미래 결정 정보가 소실돼 오답 | 이후 선택을 바꾸는 최소 변수를 상태에 포함 | 부분 문제의 **최적 부분 구조 보존** |
| 순환 의존•기저 상태 누락으로 무한 재귀•미정 참조 | **상태 전이**의 감소 방향과 종료 조건 검증 | 의존 순서와 **기저 상태** 도달 보장 |
| 큰 **상태 공간**의 전체 표 할당으로 메모리 고갈 | 실제 의존 범위만 **롤링 배열**로 유지 | 동일 결과에서 **공간복잡도** 감소 |
| 깊은 하향식 상태 연쇄로 호출 스택 초과 | 상향식 전환 또는 **명시적 스택** 적용 | 큰 입력의 **호출 스택** 초과 방지 |

#### 한줄 요약

- 필요한 상태만 정의해 답안 표의 불필요한 확장을 방지한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **실제 계산량**: 목표값을 구하는 과정에서 실제로 값을 계산하는 상태의 수이다.

</details>

- **실제 계산량**이 상태 공간보다 작으면 하향식, 대부분이면 **상향식**을 선택한다.

#### 한줄 요약

- 표에서 실제 방문할 칸이 적으면 목표부터 거슬러 가고, 거의 모든 칸을 쓴다면 시작 칸부터 차례로 채운다.
