## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **메모이제이션(Memoization)**: 재귀 호출 과정에서 한 번 계산한 부분 문제의 결과를 캐시 테이블에 저장해 두고 $O(1)$에 재사용하는 기법.
- **점화식 상태 전이(State Transition)**: 이전 하위 상태값들과 현재 상태값 간의 수학적 관계식($DP[i] = f(DP[i-1])$)을 순차 계산하는 전이 과정.
- **지수 시간 복잡도($O(2^n)$)**: 문제 크기가 커질 때 재귀 트리 분기로 인해 연산량이 기하급수적으로 폭증하는 상태.

</details>

- 정의/개념: **중복 부분 문제**의 상태값을 저장·재사용하는 설계 기법
- 배경/필요성: 재귀 호출 기반 분할 정복 적용 시 동일한 부분 문제가 반복 계산되어 발생하는 지수 시간($O(2^n)$) 연산 폭발 한계

#### 한줄 요약

- 중복 계산을 없앤 대가로 상태 수만큼의 메모리를 상시 점유하므로, 상태 공간이 크면 시간 이득보다 메모리 한계에 먼저 부딪힌다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중복 부분 문제(Overlapping Subproblems)**: 동일한 작은 하위 문제가 여러 상위 계산 경로에서 반복적으로 호출되는 특성.
- **최적 부분 구조(Optimal Substructure)**: 작은 하위 문제들의 최적해를 결합하여 상위 문제의 전체 최적해를 구성할 수 있는 성질.
- **점화식(Recurrence Relation)**: 이전 하위 상태의 해와 현재 상태의 해 사이의 관계를 나타내는 수학적 방정식.
- **기저 상태(Base Case)**: 재귀적 분할 없이 초기 조건으로 직접 정의되는 시작 상태값(DP 테이블의 초기값).

</details>

- 동일 하위 문제를 단일 상태로 캐싱해 재사용하는 **중복 부분 문제** 구조
- 부분 문제의 최적해로 전체 최적해를 구성하는 **최적 부분 구조** 기반 **점화식** 도출
- **기저 상태**로부터 의존 관계를 순차 해결하는 상태 전이 체계

#### 한줄 요약

- 최적 부분 구조를 점화식으로 정형화하여 상위 문제의 최적해를 연쇄적으로 도출한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 정의(State Definition)**: 문제를 유일하게 식별하는 파라미터 변수들의 조합($DP[i][j]$ 등).
- **타뷸레이션(Tabulation)**: 기저 상태부터 시작하여 반복문(Loop)을 통해 상향식으로 테이블을 채워나가는 방식.

</details>

```text
[동적 계획법 실행 엔진]
  │
  ├─ [상태 전이 연산기] (점화식 기반 전이 계산)
  │     ├─ 부분 문제 분해기 (상위 문제를 하위 상태로 분할)
  │     └─ 최적해 결정기 (하위 상태해 비교 및 최적값 선택)
  │
  ├─ [기저 조건 관리자] (초기값 및 탈출 경계)
  │     ├─ 초기값 설정기 (Base Case 초기화)
  │     └─ 경계 검증기 (재귀 탈출 및 인덱스 범위 확인)
  │
  └─ [상태 캐싱 테이블] (중간 결과 재사용)
        ├─ 메모이제이션 캐시 (Top-Down 재귀 캐시)
        └─ 타뷸레이션 테이블 (Bottom-Up 반복 테이블)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 상태 전이 연산기 | 하위 상태 분해 및 **점화식** 기반 상태 전이 계산 |
| 상태 캐싱 테이블 | **메모이제이션** 및 **타뷸레이션** 중간 결과 저장 |
| 기저 조건 관리자 | 재귀 탈출을 위한 **기저 상태** 초기값 보관 |

#### 한줄 요약

- 상태 계산기가 필요한 하위 상태를 구하고, 저장소가 계산한 값을 재사용한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 캐시 적중(Cache Hit)**: 호출된 상태 $DP[n]$의 값이 이미 테이블에 계산되어 존재하여 $O(1)$에 즉시 반환하는 과정.

</details>

```text
+-----------------------+
|  목표 상태 DP[N] 요청 |
+-----------+-----------+
            |
            v
     /--------------\
    <  캐시 적중(Hit) > -- Yes --> [ 저장된 DP[N] 즉시 반환 ($O(1)$) ]
     \--------------/
            | No (Miss)
            v
     /--------------\
    < 기저 상태 도달? > -- Yes --> [ Base Case 반환 및 테이블 기록 ]
     \--------------/
            | No
            v
[ 하위 의존 상태 재귀/순차 계산 ]
            |
            v
[ 점화식 적용 결합 및 DP 테이블 저장 ]
            |
            v
[ 계산 완료된 최종 상태값 반환 ]
```

분기 결과: 캐시 테이블에 이미 계산된 상태값이 존재하면 $O(1)$에 즉시 반환하여 중복 계산을 차단하고, 미계산 상태는 기저 조건 도달 여부를 판별하여 점화식을 결합한 후 테이블에 기록하여 이후 탐색의 중복을 제거한다.

**동작 원리**:
1. **상태값 조회**: 목표 또는 하위 상태가 호출되면 캐시 테이블을 먼저 조회하여 이미 계산된 결과가 있는지 확인한다.
2. **캐시 적중 분기**: 캐시 적중 시 저장된 최적값을 $O(1)$ 시간에 즉시 반환하여 하위 연산 호출을 완전 차단한다.
3. **기저 조건 판정**: 캐시 미적중 시 기저 상태(Base Case)인지 검사하여 초기 정의된 상수값을 반환하거나 테이블에 기록한다.
4. **의존 상태 전이 및 결합**: 기저 상태가 아닌 경우 하위 부분 문제들의 최적 상태값들을 계산한 뒤 점화식(Recurrence Relation)에 대입하여 현재 상태의 해를 도출한다.
5. **결과 캐싱 및 반환**: 새롭게 계산된 상태값을 DP 테이블에 기록하여 영속화하고, 상위 호출자에게 최종 상태값을 반환한다.

#### 한줄 요약

- 저장값을 먼저 확인하고, 미계산 상태의 의존값을 구해 점화식으로 결합한 뒤 저장한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **하향식(Top-Down)**: 재귀 함수와 메모이제이션을 활용하여 목표 상태에서 필요한 하위 상태만 선별 계산하는 방식.
- **상향식(Bottom-Up)**: 반복문과 타뷸레이션을 활용하여 기저 상태부터 목표 상태까지 순차적으로 테이블을 채우는 방식.
- **희소 상태 공간(Sparse State Space)**: 전체 상태 정의 범위 중에서 실제 도달 가능한 유효 상태의 비율이 극히 적은 공간.

</details>

| 구현 방식 | 하향식 (Top-Down / Memoization) | 상향식 (Bottom-Up / Tabulation) |
|:---|:---|:---|
| 적용 기준 | 도달 가능한 **희소 상태 공간** 탐색 시 | 의존 순서가 명확하고 전체 테이블 계산 시 |
| 핵심 특징 | 재귀 호출 기반 필요 상태만 **메모이제이션** | 반복문 기반 **기저 상태**부터 순차 누적 |
| 한계 | 재귀 깊이 증가 시 **스택 오버플로** 위험 | 불필요한 하위 상태까지 모두 채워 메모리 낭비 |

#### 한줄 요약

- 도달 상태가 희소하면 하향식(Memoization), 전체 상태 채움은 상향식(Tabulation) 방식을 채택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **롤링 배열(Rolling Array, 슬라이딩 윈도우)**: 현재 상태 계산에 직전 1~2개 행의 상태값만 필요할 때 모듈러 연산($i \pmod 2$)으로 공간복잡도를 $O(N^2) \to O(N)$으로 축소하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 불완전한 **상태 정의**로 미래 결정 정보가 소실되어 오답 발생 | 이후 선택을 바꾸는 최소 변수를 상태 차원에 포함 | 부분 문제의 **최적 부분 구조** 보존 |
| 순환 의존성 또는 기저 상태 누락으로 무한 재귀 호출 발생 | **상태 전이** 단조 감소 방향과 종료 조건 검증 | 의존 순서와 **기저 상태** 도달 보장 |
| 거대 상태 공간의 전체 테이블 할당으로 메모리 고갈 | 직전 의존 범위만 유지하는 **롤링 배열** 적용 | 동일 결과에서 **공간복잡도($O(n)$)** 대폭 감소 |
| 깊은 하향식 재귀 연쇄에 따른 콜 스택 오버플로 발생 | **상향식** 전환 또는 명시적 스택 적용 | 대규모 입력의 **스택 오버플로** 원천 차단 |

#### 한줄 요약

- 직전 행만 필요하면 롤링 배열로 메모리를 줄이고, 깊은 재귀는 상향식으로 전환해 스택 오버플로를 막으며, 상태 정의에 미래 결정 변수를 빠뜨리면 오답이 나온다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DP 최적화 기법 진화**: 기본 DP 외에 Convex Hull Trick, Knuth Optimization, 비트마스킹 DP 등 계산 시간과 메모리를 추가 단축하는 고급 최적화 기법의 결합.

</details>

- 배낭 문제, 최단 경로 및 강화학습(벨만 방정식)의 최적 의사결정을 지원하는 핵심 알고리즘 패러다임으로 정립되어 널리 활용되고 있으며, 향후 대규모 상태 공간의 메모리 폭발을 억제하기 위해 분산 DP 및 Convex Hull Trick 등과 결합된 고도화 최적화 구조로 확장될 것으로 전망되고, 실무 엔지니어링에서는 도달 가능한 상태 공간의 희소성과 재귀 깊이에 따라 하향식 메모이제이션과 상향식 타뷸레이션(롤링 배열 적용)을 전략적으로 선택하여 스택 오버플로와 메모리 낭비를 방지해야 한다.

#### 한줄 요약

- 도달 상태가 희소하면 하향식, 대부분이면 상향식을 선택하고 깊은 호출은 반복 방식으로 바꾼다.
