## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **동적 계획법(DP, Dynamic Programming)**: 복잡한 문제를 중복되는 부분 문제로 분할하고, 하위 문제의 해를 메모리에 저장·재사용하여 지수적 계산량을 다항 시간으로 줄이는 알고리즘 설계 패러다임.
- **점화식(Recurrence Relation)**: 이전 하위 상태값들과 현재 상태값 간의 수학적 관계를 정의한 점화 방정식.
- **메모이제이션(Memoization)**: 재귀 호출 과정에서 한 번 계산한 부분 문제의 결과를 캐시 테이블에 저장해 두고 재사용하는 기법.

</details>

- 정의/개념: 중복 부분 문제의 상태값을 캐싱 테이블에 저장해 점화식에서 재사용함으로써 중복 연산을 제거하는 **동적 계획법(DP) 최적화 알고리즘**
- 배경/필요성: 완전 탐색(DFS/재귀)은 동일한 하위 상태를 지수 횟수($O(2^n)$)로 반복 계산하여 실행 시간이 폭증하므로 **상태 저장 기반 다항 시간($O(n)$~$O(n^2)$) 최적화 필수**

#### 한줄 요약

- 부분 문제의 해를 메모이제이션 테이블에 캐싱하여 동일한 부분 문제의 중복 연산을 제거

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **중복 부분 문제(Overlapping Subproblems)**: 동일한 작은 하위 문제가 여러 상위 계산 경로에서 반복적으로 호출되는 특성.
- **최적 부분 구조(Optimal Substructure)**: 작은 하위 문제들의 최적해를 결합하여 상위 문제의 전체 최적해를 구성할 수 있는 성질.
- **기저 상태(Base Case)**: 재귀적 분할 없이 초기 조건으로 직접 정의되는 시작 상태값(DP 테이블의 초기값).

</details>

- 동일한 하위 문제들이 반복 호출되는 **중복 부분 문제**를 단일 상태로 통합해 $O(1)$ 시간 재사용
- 부분 문제의 최적해가 전체 문제의 최적해를 보장하는 **최적 부분 구조** 기반 **점화식** 도출
- **기저 상태(Base Case)**로부터 의존 관계를 순차적으로 해결해 나가는 상태 전이(State Transition) 체계

#### 한줄 요약

- 최적 부분 구조를 점화식으로 정형화하여 상위 문제의 최적해를 연쇄적으로 도출

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **상태 정의(State Definition)**: 문제를 유일하게 식별하는 파라미터 변수들의 조합($DP[i][j]$ 등).
- **타뷸레이션(Tabulation)**: 기저 상태부터 시작하여 반복문(Loop)을 통해 상향식으로 테이블을 채워나가는 방식.

</details>

```text
[ 동적 계획법 상태 전이 및 캐싱 구조 ]
┌──────────────────────────────┐
│ 상태 전이 연산기 (Engine)   │ ── 점화식 DP[i] = f(DP[i-1], DP[i-2]) 계산
├──────────────────────────────┤
│ 상태 캐싱 테이블 (DP Table) │ ── 메모이제이션(Top-down) / 타뷸레이션(Bottom-up)
├──────────────────────────────┤
│ 기저 조건 관리자 (Base Case) │ ── DP[0], DP[1] 등 재귀 탈출 초기값 보관
└──────────────────────────────┘
```

선의 의미: 상태 정의, 점화식 계산, DP 테이블 캐싱 및 기저 조건 관리 간의 동적 계획법 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 상태 전이 연산기 | 하위 상태 분해 및 **점화식** 기반 상태 전이 계산 |
| 상태 캐싱 테이블 | **메모이제이션**•타뷸레이션 캐시 보관 |
| 기저 조건 관리자 | 재귀 탈출 **초기값** 설정 및 보관 |

#### 한줄 요약

- 상태 계산기가 필요한 하위 상태를 구하고, 저장소가 계산한 값을 재사용

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **상태 캐시 적중(Cache Hit)**: 호출된 상태 $DP[n]$의 값이 이미 테이블에 계산되어 존재하여 $O(1)$에 즉시 반환하는 과정.

</details>

```text
목표 상태 DP[N] 요청
   │
   ▼
1. 상태값 조회 (DP Table Look-up)
├─ 캐시 적중(Hit): 저장된 DP[N] 값 즉시 반환 ($O(1)$)
└─ 미계산(Miss)
   │
   ▼
2. 의존 하위 상태 재귀/반복 계산 (DP[N-1], DP[N-2] 등)
   │
   ▼
3. 점화식 결합 (DP[N] = f(하위 상태))
   │
   ▼
4. 현재 상태값 저장 (DP Table 캐싱)
   │
   ▼
최종 상태값 반환
```

**동작 원리**

1. **상태값 조회**: 목표 또는 하위 상태가 이미 계산되었으면 캐시 테이블의 저장값을 즉시 반환
2. **의존 상태 계산**: 미계산 상태인 경우 기저 조건을 확인하거나 점화식이 참조하는 더 작은 하위 상태 계산
3. **점화식 결합**: 계산된 하위 상태값들을 점화식에 대입하여 현재 상태의 최적 결과 도출
4. **상태값 저장**: 계산 결과를 DP 테이블에 기록하여 향후 동일 상태 호출 시 중복 계산 방지

#### 한줄 요약

- 저장값을 먼저 확인하고, 미계산 상태의 의존값을 구해 점화식으로 결합한 뒤 저장

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **Top-Down(하향식)**: 재귀 함수와 메모이제이션을 활용하여 목표 상태에서 필요한 하위 상태만 선별 계산하는 방식.
- **Bottom-Up(상향식)**: 반복문과 타뷸레이션을 활용하여 기저 상태부터 목표 상태까지 순차적으로 테이블을 채우는 방식.

</details>

| 비교 항목 | 하향식 (Top-Down / Memoization) | 상향식 (Bottom-Up / Tabulation) |
|:---|:---|:---|
| 적용 기준 | 도달 가능한 **희소 상태 공간(Sparse Space)** | 의존 순서가 명확하고 전체 테이블 계산 시 |
| 핵심 특징 | 재귀 호출 + 필요 상태만 **메모이제이션** | 반복문(Loop) + **기저 상태**부터 순차 누적 |
| 한계 및 위험 | 재귀 깊이 증가 시 **스택 오버플로** 위험 | 불필요한 하위 상태까지 모두 채워 메모리 낭비 |

#### 한줄 요약

- 도달 상태가 희소하면 하향식(Memoization), 전체 상태 채움은 상향식(Tabulation) 방식을 채택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **롤링 배열(Rolling Array, 슬라이딩 윈도우)**: 현재 상태 계산에 직전 1~2개 행의 상태값만 필요할 때 모듈러 연산($i \pmod 2$)으로 공간복잡도를 $O(N^2) \to O(N)$으로 축소하는 기법.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 불완전한 **상태 정의**로 미래 결정 정보가 소실돼 오답 | 이후 선택을 바꾸는 최소 변수를 상태 차원에 포함 | 부분 문제의 **최적 부분 구조 보존** |
| 순환 의존•기저 상태 누락으로 무한 재귀•미정 참조 | **상태 전이**의 단조 감소 방향과 종료 조건 검증 | 의존 순서와 **기저 상태** 도달 보장 |
| 큰 **상태 공간**의 전체 표 할당으로 메모리 고갈 | 직전 의존 범위만 유지하는 **롤링 배열** 적용 | 동일 결과에서 **공간복잡도($O(N)$)** 대폭 감소 |
| 깊은 하향식 상태 연쇄로 호출 스택 초과 | **상향식(Bottom-Up)** 전환 또는 명시적 스택 적용 | 큰 입력의 **스택 오버플로** 원천 차단 |

#### 한줄 요약

- 직전 행만 필요하면 롤링 배열로 메모리를 줄이고, 깊은 재귀는 상향식으로 전환해 스택 오버플로를 막으며, 상태 정의에 미래 결정 변수를 빠뜨리면 오답이 나온다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **DP 최적화 기법 진화**: 기본 DP 외에 Convex Hull Trick, Knuth Optimization, 비트마스킹 DP 등 계산 시간과 메모리를 추가 단축하는 고급 최적화 기법의 결합.

</details>

- 도달 상태가 희소하면 **하향식(Memoization)**, 전체 상태 채움은 **상향식(Tabulation)** 선택

#### 한줄 요약

- 도달 상태가 희소하면 하향식, 대부분이면 상향식을 선택하고 깊은 호출은 반복 방식으로 바꿈
