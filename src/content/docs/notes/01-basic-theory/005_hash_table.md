## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **해시 테이블(Hash Table)**: 키를 버킷 인덱스로 변환하여 키·값 쌍을 $O(1)$ 평균 시간에 저장 및 조회함.
- **버킷(Bucket)**: 해시 테이블에서 동일 인덱스에 할당되는 데이터 엔트리 저장 메모리 공간.

- **비교 횟수(Comparison Count)**: 해시 충돌 발생 시 체인 또는 탐사 경로에서 목표 키를 찾기 위해 수행한 동등성 대조 횟수.
</details>

- 정의/개념: 키를 해시 함수로 연산하여 버킷 인덱스로 변환하고 키·값 데이터를 관리하는 **해시 테이블 자료구조**
- 배경/필요성: 무순서 키 집합의 선형 탐색은 입력 증가만큼 **비교 횟수** 증가

#### 한줄 요약

- 키를 해시 함수로 연산해 결정론적 버킷 인덱스를 도출함으로써 $O(1)$의 평균 탐색 성능을 제공한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **균등 해싱 가정(SUHA, Simple Uniform Hashing Assumption)**: 각 키가 모든 버킷에 독립적이고 동일한 확률로 고르게 매핑된다는 분석 전제.
- **충돌(Collision)**: 서로 다른 두 개 이상의 키가 동일한 버킷 인덱스로 변환되는 현상.
- **적재율(Load Factor, $\alpha$)**: 저장된 엔트리 개수($n$)를 전체 버킷 수($m$)로 나눈 자원 점유 비율.
- **충돌 해결 방식(Collision Resolution Method)**: 충돌 발생 시 체이닝 또는 탐사를 통해 공간을 재배치하는 규칙 체계.

</details>

![해시 테이블 적재율별 실패 조회 비용](/study/diagrams/hash-load-factor.svg)

> 적재율 0.9 육박 시 개방주소법 탐사 횟수 급증 및 체이닝 길이 확장에 따른 성능 비교 양상

- **균등 해싱 가정** 기반의 상수 시간($O(1)$) 버킷 직접 접근 메커니즘
- 충돌 발생 시 **체이닝 및 개방주소법** 등 해결 방식 적용
- **적재율($\alpha$)** 관리를 통한 탐색·삽입 성능 저하 방지

#### 한줄 요약

- 동일한 버킷에 해시 충돌이 빈발할수록 후보 체인 및 탐사 길이가 증가하여 $O(N)$으로 성능이 저하된다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해시 함수(Hash Function)**: 임의 길이 키를 고정 크기 정수 해시값 및 버킷 인덱스로 매핑하는 매핑 함수.
- **엔트리(Entry)**: 해시 테이블에 함께 적재되는 키(Key)와 값(Value)의 바인딩 단위.
- **체이닝(Chaining)**: 충돌 엔트리들을 연결 리스트나 트리 구조로 연결 적재함.
- **개방 주소법(Open Addressing)**: 충돌 발생 시 테이블 내 다른 빈 버킷을 규칙적으로 탐사하여 저장함.
- **해시값(Hash Value)**: 해시 함수가 키로부터 산출하며 버킷 인덱스 계산에 쓰는 정수값.

</details>

```text
해시 테이블 구조
├─ 해시 함수
├─ 버킷 배열
└─ 충돌 해결 구조
```

가지의 의미: 인덱스 산정, 데이터 저장, 충돌 관리를 위한 기능별 책임 분할 구조

| 구성요소 | 책임 |
|:---|:---|
| 해시 함수 | 키를 **해시값**•인덱스로 변환 |
| 버킷 배열 | 인덱스별 **키•값 엔트리** 저장 |
| 충돌 해결 구조 | **체이닝•개방 주소법**으로 원본 키 대조 |

#### 한줄 요약

- 해시 함수가 버킷을 정하고 충돌 해결 구조가 원본 키를 대조해 엔트리를 찾는다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **버킷 인덱스(Bucket Index)**: 해시값을 버킷 배열 크기로 모듈러 연산하여 산출한 실제 메모리 배열 주소.
- **원본 키 대조(Key Equality Check)**: 충돌 후보 엔트리의 키와 검색 대상 키의 일치 여부를 정밀 검증함.
- **탐사 순서(Probe Sequence)**: 개방 주소법 적용 시 충돌 후 차선책으로 검사할 버킷들의 순차적 위치.

- **다음 후보 이동(Probe to Next Candidate)**: 해시 충돌 발생 시 개방주소법의 탐사 순서나 체이닝의 다음 노드 포인터로 이동하는 절차.
</details>

```text
조회 키
   │
   ▼
1. 버킷 인덱스 산정
   │
   ▼
2. 원본 키 대조
├─ 일치: 조회 결과 반환
└─ 불일치
   ├─ 후보 소진: 미발견 반환
   └─ 후보 존재
      │
      ▼
   3. 다음 후보 이동
      │
      └─ 원본 키 대조로 반복
```

**동작 원리**

1. 버킷 인덱스 산정: 해시 연산 기반 유효 버킷 인덱스 도출
2. 원본 키 대조: 버킷 내 대상 엔트리와 조회 키 동등성 검증
3. 다음 후보 이동: 불일치 시 체인 또는 탐사 순서에 따라 차선 후보 버킷 이동

#### 한줄 요약

- 해시 인덱스 도출, 원본 키 동등성 검증, 다음 후보 탐사 루프를 거쳐 엔트리를 탐색/반환한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **균형 이진 탐색 트리(BBST, Balanced Binary Search Tree)**: 키 순서 보존 및 범위 조회를 $O(\log n)$ 시간에 보장함.
- **정렬 배열(Sorted Array)**: 키 순서대로 연속 메모리에 저장하여 이진 탐색을 지원하는 배열.
- **재균형(Rebalancing)**: 트리 높이 편향 방지를 위해 노드 구조를 재회전하는 트랜스포메이션.
- **선형 퇴화(Linear Degradation)**: 해시 충돌 집중으로 인해 조회 복잡도가 최악의 경우 $O(n)$으로 악화됨.
- **단건 조회(Point Query)**: 특정 키 단 한 건의 존재 여부 및 값을 정확히 찾아내는 탐색.
- **조회 중심 워크로드(Read-Heavy Workload)**: 데이터 수정 대비 검색 요청 비율이 압도적으로 높은 시스템 부하 조건.

- **범위 탐색(Range Search)**: 특정 구간(하한~상한)에 속하는 모든 키-값 쌍을 순서대로 조회하는 연산.
- **균형 높이(Balanced Height)**: 트리의 모든 리프 노드까지의 깊이 차이를 일정 범위 내로 유지하여 $O(\log n)$ 탐색을 보장하는 특성.
- **연속 공간(Contiguous Space)**: 메모리 상에 빈틈없이 연속된 바이트 블록으로 배열 요소를 배치하는 저장 방식.
</details>

| 탐색 자료구조 | 해시 테이블 | 균형 이진 탐색 트리 | 정렬 배열 |
|:---|:---|:---|:---|
| 적용 기준 | 정확 키 **단건 조회** | **범위 탐색**•정렬 순회 | 삽입이 드문 **조회 중심 워크로드** |
| 핵심 특징 | **해시값**으로 버킷 접근 | **균형 높이**로 키 순서 유지 | **연속 공간**•이진 탐색 |
| 한계 | 충돌 집중 시 **선형 퇴화** | 갱신 시 **재균형** 비용 | 중간 삽입 시 원소 이동 |

> 요약: 정확 키 단건 조회 시 **해시 테이블**, 범위 검색 시 **균형 이진 탐색 트리** 적용

#### 한줄 요약

- 점조회(Point Query)에는 해시 테이블, 범위/순서 탐색에는 균형 이진 탐색 트리, 변경이 드문 정적 집합에는 정렬 배열을 선택한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **재해싱(Rehashing)**: 버킷 배열 크기를 2배 등으로 확장하고 기존 엔트리들의 해시 인덱스를 재산정함.
- **무작위 해시 시드(Randomized Hash Seed)**: 런타임마다 임의 난수를 시드로 적용하여 해시 예측 공격을 차단함.
- **해시 충돌 DoS(Hash Collision Denial of Service)**: 의도적 동일 버킷 충돌 유발로 시스템 조회를 선형 퇴화시키는 공격 방식.
- **동등성 계약(Equals & HashCode Contract)**: 두 객체가 동등하면 동일한 해시 값을 생성해야 한다는 객체 규약.
- **충돌 집중(Clustering)**: 개방 주소법 등에서 연속된 버킷에 데이터가 뭉치는 집단화 현상.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 키 분포의 **충돌 집중**으로 버킷 탐색이 선형 퇴화 | 데이터 분포에 맞는 **해시 함수**와 분산 검증 | **균등 해싱 가정**에 가까운 분포 회복 |
| 높은 **적재율**로 개방 주소 탐사 급증•빈 버킷 고갈 | 임계 적재율 이전 확장•**재해싱** | 탐사 길이 감소와 적재율 여유 확보 |
| **동등성 계약** 위반으로 동등 키의 조회 누락 | 동등 비교와 해시 함수에 동일 필드 사용 | 키 동등성 계약의 일관성 확보 |
| 외부 입력의 **해시 충돌 DoS**로 조회 지연 집중 | **무작위 해시 시드**와 버킷 길이 제한 | 의도적 충돌의 **선형 퇴화** 억제 |

#### 한줄 요약

- 임계 적재율 전에 버킷을 확장·재해싱해 평균 탐사 길이 증가를 억제한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **적재율 통제(Load Factor Control)**: 임계 적재율 도달 시 자동 리사이징을 수행하여 충돌 탐사 길이를 차단함.

</details>

- 단건 조회와 **적재율 통제**가 가능하면 해시, 범위 조회면 균형 트리 선택

#### 한줄 요약

- 점조회 성능 최적화를 위한 자료구조로서, 적재율 관리 및 해시 충돌 억제(Uniform Hashing/Seed)를 집행하여 선형 퇴화를 방지 체계 적용
