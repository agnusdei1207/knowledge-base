## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **해시 테이블(Hash Table)**: 키를 해시 함수로 변환하여 버킷 인덱스를 도출하고 키·값 쌍을 평균 $O(1)$ 시간에 저장 및 조회하는 자료구조.
- **버킷(Bucket)**: 해시 테이블에서 동일 인덱스에 할당되는 데이터 엔트리 저장 메모리 공간.
- **비교 횟수(Comparison Count)**: 해시 충돌 발생 시 체인 또는 탐사 경로에서 목표 키를 찾기 위해 수행한 동등성 대조 횟수.

</details>

- 정의/개념: 키를 해시 함수로 연산하여 버킷 인덱스로 매핑한 후 키·값 쌍을 평균 $O(1)$ 시간 복잡도로 저장 및 검색하는 연관 배열 자료구조
- 배경/필요성: 비정렬 대용량 키 집합의 선형 탐색 시 데이터 증가에 따른 **비교 횟수** 급증 및 응답 성능 저하 발생

#### 한줄 요약

- 키를 해시 함수로 연산해 결정론적 버킷 인덱스를 도출함으로써 $O(1)$의 평균 탐색 성능을 제공

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **단순 균등 해싱 가정(Simple Uniform Hashing Assumption, SUHA)**: 각 키가 모든 버킷에 독립적이고 동일한 확률로 고르게 매핑된다는 분석 전제.
- **충돌(Collision)**: 서로 다른 두 개 이상의 키가 동일한 버킷 인덱스로 변환되는 현상.
- **적재율(Load Factor, $\alpha$)**: 저장된 엔트리 개수($n$)를 전체 버킷 수($m$)로 나눈 자원 점유 비율.
- **충돌 해결 방식(Collision Resolution Method)**: 충돌 발생 시 체이닝 또는 개방 주소법을 통해 공간을 재배치하는 규칙 체계.

</details>

![해시 테이블 적재율별 실패 조회 비용](/study/diagrams/hash-load-factor.svg)

> 적재율 0.9 육박 시 개방주소법 탐사 횟수 급증 및 체이닝 길이 확장에 따른 성능 비교 양상

- **균등 해싱 가정** 기반의 상수 시간($O(1)$) 버킷 직접 접근 메커니즘
- 충돌 발생 시 **체이닝 및 개방주소법** 등 해결 방식 적용
- **적재율($\alpha$)** 관리를 통한 탐색·삽입 성능 저하 방지

#### 한줄 요약

- 동일한 버킷에 해시 충돌이 빈발할수록 후보 체인 및 탐사 길이가 증가하여 $O(N)$으로 성능이 저하

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **해시 함수(Hash Function)**: 임의 길이 키를 고정 크기 정수 해시값 및 버킷 인덱스로 매핑하는 함수.
- **해시값(Hash Value)**: 해시 함수에 키를 입력하여 도출되는 고정 길이의 정수 주소값.
- **엔트리(Entry)**: 해시 테이블에 함께 적재되는 키(Key)와 값(Value)의 바인딩 단위.
- **체이닝(Chaining)**: 충돌 엔트리들을 연결 리스트나 트리 구조로 연결 적재하는 방식.
- **개방 주소법(Open Addressing)**: 충돌 발생 시 테이블 내 다른 빈 버킷을 규칙적으로 탐사하여 저장하는 방식.

</details>

```text
[ 해시 테이블 아키텍처 및 충돌 처리 ]
┌──────────────────────────────┐
│ 해시 함수 (Hash Function)    │ ── h(key) = key mod m 균등 분배
├──────────────────────────────┤
│ 버킷 배열 (Bucket Array)     │ ── 인덱스 0 ~ m-1 물리 슬롯 배열
├──────────────────────────────┤
│ 충돌 해결기 (Chaining / OA)  │ ── 연결 리스트 체이닝 및 선형/이차/이중 탐사
├──────────────────────────────┤
│ 엔트리 저장소 (Key-Value)    │ ── 원본 Key 및 데이터 Value 보관
└──────────────────────────────┘
```

선의 의미: 해시 함수 인덱싱, 버킷 배열, 충돌 해결 메커니즘 및 엔트리 저장소 간의 해시 테이블 구조도.

| 구성요소 | 책임 |
|:---|:---|
| 해시 함수 | 키를 **해시값** 및 버킷 인덱스로 변환 |
| 버킷 배열 | 인덱스별 **엔트리** 슬롯 제공 |
| 충돌 해결기 | **체이닝**•개방 주소법으로 충돌 엔트리 재배치 |
| 엔트리 저장소 | 원본 키•값 쌍 보관 및 대조 |

#### 한줄 요약

- 해시 함수가 버킷을 정하고 충돌 해결 구조가 원본 키를 대조해 엔트리를 탐색

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **버킷 인덱스(Bucket Index)**: 해시값을 버킷 배열 크기로 모듈러 연산하여 산출한 실제 메모리 배열 주소.
- **동등성 검증(Equality Check)**: 버킷 내 대상 엔트리와 조회 키의 실제 일치 여부를 대조하는 연산.
- **탐사 순서(Probe Sequence)**: 개방 주소법 적용 시 충돌 후 차선책으로 검사할 버킷들의 순차적 위치.

</details>

```text
조회 키
   │
   ▼
1. 버킷 인덱스 산정
   │
   ▼
2. 원본 키 대조
├─ 일치: 조회 결과 반환
└─ 불일치
   ├─ 후보 소진: 미발견 반환
   └─ 후보 존재
      │
      ▼
   3. 다음 후보 이동
      │
      └─ 원본 키 대조로 반복
```

**동작 원리**

1. **버킷 인덱스 산정**: 해시 연산 기반 유효 **버킷 인덱스** 도출
2. **원본 키 대조**: 버킷 내 대상 엔트리와 조회 키의 **동등성 검증** 수행
3. **다음 후보 이동**: 불일치 시 체인 또는 **탐사 순서**에 따라 다음 후보로 이동하여 반복

#### 한줄 요약

- 해시 인덱스 도출, 원본 키 동등성 검증, 다음 후보 탐사 루프를 거쳐 엔트리를 탐색 및 반환

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **균형 이진 탐색 트리(Balanced Binary Search Tree, BBST)**: 키 순서 보존 및 범위 조회를 $O(\log n)$ 시간에 보장하는 트리 구조(AVL, Red-Black).
- **정렬 배열(Sorted Array)**: 키 순서대로 연속 메모리에 저장하여 이진 탐색을 지원하는 배열.
- **균형 높이(Balanced Height)**: 트리의 좌우 서브트리 높이 차를 제한하여 최대 탐색 깊이를 $O(\log n)$으로 유지하는 구조적 성질.
- **선형 퇴화(Linear Degradation)**: 해시 충돌 집중으로 인해 조회 복잡도가 최악의 경우 $O(n)$으로 악화되는 현상.

</details>

| 비교 항목 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 (BBST) | 정렬 배열 (Sorted Array) |
|:---|:---|:---|:---|
| 적용 기준 | 정확한 키 기반 **단건 조회** 최우선 시 | **범위 탐색** 및 키 정렬 순회 요구 시 | 데이터 삽입이 드문 **조회 중심 워크로드** |
| 핵심 특징 | **해시값** 기반 버킷 $O(1)$ 즉각 접근 | **균형 높이** 유지로 $O(\log n)$ 시간 보장 | **연속 공간** 배치 및 $O(\log n)$ 이진 탐색 |
| 한계 및 위험 | 충돌 집중 시 최악 $O(n)$ **선형 퇴화** | 노드 갱신 시 트리 **재균형** 오버헤드 | 중간 삽입/삭제 시 $O(n)$ 원소 이동 발생 |

#### 한줄 요약

- 점조회(Point Query)에는 해시 테이블, 범위/순서 탐색에는 균형 이진 탐색 트리, 변경이 드문 정적 집합에는 정렬 배열을 선택

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **재해싱(Rehashing)**: 버킷 배열 크기를 2배 등으로 확장하고 기존 엔트리들의 해시 인덱스를 재산정하는 작업.
- **무작위 해시 시드(Randomized Hash Seed)**: 런타임마다 임의 난수를 시드로 적용하여 해시 예측 공격을 차단하는 기법(SipHash 등).
- **동등성 계약(Equality Contract)**: Java의 equals와 hashCode처럼 두 객체가 동등하면 해시 코드도 반드시 같아야 한다는 일관성 규칙.
- **해시 충돌 서비스 거부 공격(Hash Collision Denial of Service, Hash Collision DoS)**: 의도적 동일 버킷 충돌 유발로 시스템 조회를 선형 퇴화시키는 서비스 거부 공격.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 키 분포의 **충돌 집중**으로 버킷 탐색이 선형 퇴화 | 데이터 분포에 맞는 **해시 함수** 및 분산 검증 | **균등 해싱 가정**에 가까운 분포 회복 |
| 높은 **적재율**로 개방 주소 탐사 급증•빈 버킷 고갈 | 임계 적재율($\alpha \ge 0.7$) 이전 확장•**재해싱** | 탐사 길이 감소와 적재율 여유 확보 |
| **동등성 계약** 위반으로 동등 키의 조회 누락 | 동등 비교(equals)와 해시(hashCode)에 동일 필드 사용 | 키 동등성 계약의 일관성 확보 |
| 외부 입력의 **해시 충돌 DoS**로 조회 지연 집중 | **무작위 해시 시드**와 버킷 길이 제한 | 의도적 충돌의 **선형 퇴화** 억제 |

#### 한줄 요약

- 적재율이 0.7을 넘기 전에 재해싱으로 확장하고, 외부 입력에는 SipHash 무작위 시드를 적용해 의도적 충돌 DoS를 막으며, equals와 hashCode가 같은 필드를 써야 조회 누락이 없다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **적재율 통제(Load Factor Control)**: 임계 적재율 도달 시 자동 리사이징을 수행하여 충돌 탐사 길이를 차단하는 기법.

</details>

- 단건 점조회와 적재율 통제 중심은 **해시 테이블**, 범위 검색과 정렬 순회는 **균형 이진 탐색 트리** 선택

#### 한줄 요약

- 단건 점조회가 핵심이면 해시 테이블로 O(1) 접근을 확보하고, 범위 검색이나 정렬 순회가 필요하면 균형 이진 탐색 트리를 선택한다.
