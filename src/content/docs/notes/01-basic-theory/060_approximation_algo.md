## Ⅰ. 개요

<details><summary>핵심 용어</summary>

- **근사 알고리즘**: 다항 시간에 실행되며 최적해 대비 해의 품질 한계를 보장하는 알고리즘
- **NP-난해 문제**: 모든 NP 문제 이상의 계산 난도를 가져 대규모 최적해 탐색이 어려운 문제

</details>

- 정의/개념: **근사 알고리즘**은 NP-난해 최적화 문제에서 다항 시간에 실행 가능 해를 구하고 최적해 대비 품질 한계를 근사비로 보장하는 **알고리즘**
- 배경/필요성: NP-난해 최적화 문제는 입력이 커질수록 정확한 최적해 탐색 비용이 급증해 **대규모 처리가 어려움**

### 쉽게 이해하기 (학습용)
- 근사 알고리즘은 빠르게 구한 배송 경로가 최적 경로의 두 배를 넘지 않는다는 식으로 손해 한계를 보장한다.

## Ⅱ. 특징

<details><summary>핵심 용어</summary>

- **실행 가능 해**: 원래 문제의 모든 제약 조건을 만족하는 후보 해
- **근사비 $\rho$**: 최악의 근사해와 최적해 사이의 품질 비율
- **PTAS·FPTAS**: 허용 오차에 따라 최적해에 가까운 해를 제공하는 다항 시간 근사 스킴

</details>

- **다항 시간** 안에 **실행 가능 해** 도출
- 최적해 대비 **근사비**로 최악 입력 **품질 보장**
- 허용 오차 축소 시 **PTAS•FPTAS**의 계산 비용 증가

### 쉽게 이해하기 (학습용)
- 배송 경로의 손해 상한 눈금을 최적선에 가까이 조일수록 계산 시계가 더 오래 도는 장면이다.

## Ⅲ. 구조 및 구성요소

<details><summary>핵심 용어</summary>

- **목적 함수·제약 조건**: 최소화·최대화할 값과 허용되는 해의 범위를 정의하는 요소
- **완화·라운딩**: 제약을 풀어 연속 해를 구한 뒤 원래 정수 제약을 만족하도록 바꾸는 방법
- **최적해 경계**: 근사비 증명에 사용하는 최적값의 하한이나 상한

</details>

```mermaid
block
    columns 2
    M["문제 모델"]
    C["해 구성기"]
    V["실행 가능성 검사"]
    B["근사비 분석"]
    M --- C
    C --- V
    V --- B
```

| 구성요소 | 책임 |
|:---|:---|
| 문제 모델 | 목적 함수•제약 조건으로 **최적화 목표**와 실행 가능 영역 정의 |
| 해 구성기 | 탐욕법•완화•라운딩으로 **근사 후보 해** 산출 |
| 실행 가능성 검사 | 후보 해의 **원래 제약 충족** 여부 판정 |
| 근사비 분석 | 근사값•최적해 경계로 **최악 품질 경계** 산출 |

### 쉽게 이해하기 (학습용)
- 문제 설계도가 후보 공장을 지나 제약 검문소와 품질 저울에서 사용 가능 도장을 받는 장면이다.

## Ⅳ. 흐름도

<details><summary>핵심 용어</summary>

- **근사값 $\mathrm{ALG}$**: 근사 알고리즘이 산출한 목적 함수 값
- **최적값 $\mathrm{OPT}$**: 같은 입력에서 가능한 가장 좋은 목적 함수 값
- **근사비 증명**: 두 값의 비가 정해진 상한을 넘지 않음을 보이는 과정

</details>

```mermaid
sequenceDiagram
    participant D as 문제 설계자
    participant M as 문제 모델
    participant C as 해 구성기
    participant V as 실행 가능성 검사
    participant B as 근사비 분석
    D->>M: 문제 정의
    M->>C: 1. 목적 함수•제약 조건
    C->>V: 2. 근사 후보 해
    M->>B: 3. 최적해 하한•상한
    V->>B: 실행 가능 해
    B-->>D: 근사비 증명
    D->>M: 채택 결정
```

$$\text{최소화}: \mathrm{ALG}/\mathrm{OPT}\le\rho,\quad \text{최대화}: \mathrm{OPT}/\mathrm{ALG}\le\rho$$

**동작 원리**

- **1. 목적 함수•제약 조건**: 최적화 목표와 허용 해 정의
- **2. 근사 후보 해**: 탐욕법•완화•라운딩 산출물
- **3. 최적해 하한•상한**: 근사비 증명의 비교 기준

### 쉽게 이해하기 (학습용)
- 후보 해가 제약 검문소를 통과한 뒤 최적해 경계 추와 품질 저울에서 비교되는 장면이다.

## Ⅴ. 종류 및 비교

<details><summary>핵심 용어</summary>

- **정확 알고리즘**: 가능한 해를 충분히 탐색해 최적해를 보장하는 방법
- **휴리스틱**: 경험 규칙으로 빠르게 해를 찾지만 일반적인 최악 품질 경계는 보장하지 않는 방법
- **성능 보장**: 모든 입력에서 근사해 품질이 증명된 범위 안에 든다는 약속

</details>

| 해법 유형 | 근사 알고리즘 | 정확 알고리즘 | 휴리스틱 |
|:---|:---|:---|:---|
| 적용 기준 | **대규모 입력**에 품질 보장이 필요한 경우 | **소규모 입력**에 최적해가 필요한 경우 | 품질 보장보다 **응답 시간**이 중요한 경우 |
| 핵심 특징 | **근사비** 보장 탐색 | **최적해** 탐색 | **경험 규칙** 탐색 |
| 한계 | 증명 상한이 실제보다 **느슨한 경계** | 입력 증가 시 **지수 시간** 폭증 | **최악 품질** 보장 부재 |

> 요약: 증명 가능한 **성능 보장**이 필요한지에 따라 방법 선택

### 쉽게 이해하기 (학습용)
- 근사는 보증서 있는 빠른 상품, 정확 해법은 완벽하지만 늦은 주문품, 휴리스틱은 보증 없는 즉석품인 장면이다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>핵심 용어</summary>

- **복구 절차**: 제약을 위반한 후보를 수정해 실행 가능한 해로 만드는 처리
- **허용 오차 $\varepsilon$**: 근사해가 최적해에서 벗어날 수 있는 품질 한계
- **하한 강화**: 최적값의 추정 하한을 높여 근사해 품질 평가를 더 정확하게 만드는 작업

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 근사해가 **원래 제약을 위반** | 실행 가능성 검사와 **복구 절차** 적용 | **사용 가능한 해** 보장 |
| 증명 근사비가 **업무 허용 오차 초과** | 정확 알고리즘•**PTAS•FPTAS** 대안 비교 | **품질 요구** 충족 |
| 이론 보장보다 **실제 해가 지속적으로 나쁨** | 대표•최악 입력 벤치마크와 **하한 강화** | **품질 경계 실효성** 검증 |
| 작은 입력에도 **근사만 사용** | 입력 규모 기준으로 **정확 해법 전환** | **불필요한 품질 손실** 방지 |

### 쉽게 이해하기 (학습용)
- 모든 간선에 선택 정점 스티커가 닿는지 확인하고 선택 수가 최적 하한의 두 배 이내인지 재는 장면이다.

## Ⅶ. 결론

<details><summary>핵심 용어</summary>

- **업무 허용선**: 서비스에서 받아들일 수 있는 해 품질 손실의 최대 기준
- **해법 전환**: 입력 규모와 품질 요구에 따라 근사 방식에서 정확 방식으로 바꾸는 결정

</details>

- **근사비**가 허용 오차를 넘으면 **정확 알고리즘** 전환

### 쉽게 이해하기 (학습용)
- 품질 보증서의 손해 상한이 서비스 허용선을 넘으면 느린 정확 해법 스위치를 켜는 장면이다.
