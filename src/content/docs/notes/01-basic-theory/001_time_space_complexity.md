## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **점근적 증가율(Asymptotic Growth Rate)**: 입력 크기 $N$이 무한히 커질 때 기본 연산 횟수나 메모리 소모량이 증가하는 점근적 비율.
- **자원 한도(Resource Limit)**: 서비스 수준 협약(SLA)에서 허용하는 최대 실행 시간 및 하드웨어 물리 메모리 임계치.

</details>

- 정의/개념: 입력 크기($N$) 증가에 따른 기본 연산 횟수와 메모리 소모량의 **점근적 증가율**을 수식화하는 알고리즘 정량 분석 체계
- 배경/필요성: 하드웨어 사양과 런타임 환경에 종속적인 실측 벤치마크만으로는 대규모 입력 시의 자원 고갈을 사전에 예측할 수 없는 알고리즘 확장성 평가 한계

#### 한줄 요약

- 입력 규모가 커질 때 연산 횟수와 메모리 점유가 얼마나 빠르게 증가하는지 비교한다.

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지배항(Dominant Term)**: 입력이 커질수록 전체 증가율을 결정하는 가장 빠르게 증가하는 최고차 항.
- **빅오(Big-O)**: 입력 증가에 따른 비용의 점근적 상한(Asymptotic Upper Bound) 표기.
- **빅세타(Big-Theta)**: 입력 증가에 따른 비용의 정확한 점근 차수(Asymptotic Tight Bound) 표기.
- **빅오메가(Big-Omega)**: 입력 증가에 따른 비용의 점근적 하한(Asymptotic Lower Bound) 표기.
- **시간·공간 상충(Time-Space Tradeoff)**: 중간 결과를 저장해 재계산 시간을 줄이는 대신 추가 메모리를 사용하는 관계.
- **최악 사례(Worst Case)**: 동일 입력 크기에서 자원 소모가 가장 큰 입력 사례.

</details>

![대표 시간복잡도의 입력 크기별 증가율](/study/diagrams/complexity-growth-rates.svg)

> 입력 크기가 커질수록 붉은 O(n²)와 초록 O(n log n)이 파란 O(log n)•O(n)보다 빠르게 벌어지며, 기본 연산량을 정규화한 이론적 증가율임

- **점근적 증가율** 기반 **빅오**·**빅세타**·**빅오메가** 표기로 비용 상한·정밀 차수·하한 분류
- 중간 결과 저장과 재연산 간의 **시간·공간 상충** 관계
- 최선·평균·**최악 사례** 구분으로 입력 분포별 알고리즘 선택

#### 한줄 요약

- 하드웨어 차이를 제외하고 입력 규모에 따른 시간·공간 비용의 상한과 하한을 비교한다.

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **계산 모델(Computational Model)**: 기본 연산 비용을 균일하다고 가정하여 하드웨어 차이를 배제하는 분석 모델.
- **기본 연산(Basic Operation)**: 비교·대입 등 실행 횟수로 전체 시간 비용을 대변하는 핵심 연산.
- **보조 공간(Auxiliary Space)**: 입력 데이터 자체를 제외하고 알고리즘 수행 시 추가로 요구되는 메모리.
- **점근 차수(Asymptotic Order)**: 상수와 하위항을 배제하고 지배항의 증가율을 기준으로 분류한 비용 등급.

</details>

```text
[복잡도 분석 체계]
  │
  ├─ [단위 계산 모델] (기본 연산·단위 메모리 기준)
  │
  ├─ [비용 함수 추출]
  │     ├─ [시간 함수 T(N)] (루프·재귀 실행 횟수)
  │     └─ [공간 함수 S(N)] (보조 메모리·호출 스택)
  │
  └─ [점근 차수 판정]
        ├─ [지배항 추출] (상수·하위항 제거)
        └─ [복잡도 분류] (O·Ω·Θ 점근 한계 확정)
```

- 선의 의미: 계층 구조 및 상하위 포함 관계를 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| **계산 모델** | **기본 연산** 단위 비용 규정 |
| 시간 분석 | 입력 크기별 **기본 연산** 수행 횟수 산정 |
| 공간 분석 | 입력 크기별 최대 **보조 공간** 산정 |
| 점근 차수 판정 | **지배항** 및 **점근 차수** 기준 증가율 분류 |

#### 한줄 요약

- 계산 모델에서 단위 연산을 정한 뒤 시간·공간 비용을 점근 차수로 분류한다.

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비용 함수(Cost Function)**: 입력 크기에 따른 시간 또는 공간 사용량의 증가 추세를 나타내는 함수.

</details>

```text
[입력 데이터 규모 (N)]
          │
          ▼
[1. 계산 모델 수립: 단위 기본 연산(비교/대입) 및 메모리 기준 정의]
          │
          ▼
[2. 시간 비용 분석: 루프/재귀 호출 횟수 집계 및 T(N) 함수 산출]
          │
          ▼
[3. 공간 비용 분석: 고정 공간 및 가변 보조 공간(스택/버퍼) 집계]
          │
          ▼
[4. 최고차 지배항 추출: 상수 계수 및 저차항 제거]
          │
          ▼
[5. 점근 차수 판정: Big-O, Omega, Theta 복잡도 등급 확정]
```

분기 결과: 점근 차수 판정에서 상수와 저차항을 소거하므로 차수가 서로 다른 알고리즘은 수학적 점근 분석만으로 우열이 확정되나, 동일 차수로 판정된 후보군은 런타임 캐시 적중률과 상수 계수를 측정하는 실측 벤치마크를 통해 최적 후보를 판별함

**동작 원리**:
1. 분석 대상 알고리즘의 실행 환경과 하드웨어 의존성을 배제하기 위해 비교, 대입, 산술 연산 등 단일 사이클 기본 연산 단위를 규정함.
2. 입력 크기 $N$에 따른 루프 실행 횟수와 재귀 호출 트리 깊이를 집계하여 입력 크기 대비 총 연산 횟수를 나타내는 시간 **비용 함수** $T(N)$을 도출함.
3. 입력 데이터 저장 공간을 제외하고 알고리즘 구동을 위해 런타임에 동적으로 요구되는 호출 스택, 캐시 버퍼 크기를 집계하여 보조 공간 함수 $S(N)$을 산출함.
4. 산출된 시간 및 공간 비용 다항식에서 계수와 저차항을 제거하고 입력 $N$ 증가 시 성장을 주도하는 최고차 **지배항**을 분리함.
5. 분리된 지배항의 성장률에 따라 점근적 상한(**빅오**), 하한(빅오메가), 정밀 차수(빅세타) 집합으로 분류하여 최종 복잡도 등급을 확정함.

#### 한줄 요약

- 계산 기준을 세우고 시간·공간 비용 함수를 구한 뒤 지배항으로 점근 차수를 판정한다.

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시간복잡도(Time Complexity)**: 입력 크기 증가에 따른 기본 연산 횟수의 점근적 증가 정도.
- **공간복잡도(Space Complexity)**: 입력 크기 증가에 따른 최대 메모리 사용량의 점근적 증가 정도.
- **응답시간(Response Time)**: 시스템이 요청을 처리하고 결과를 반환하는 데 소요되는 시간.
- **메모리 예산(Memory Budget)**: 시스템이 알고리즘에 할당할 수 있는 최대 가용 메모리 한도.
- **추가 공간(Extra Space)**: 호출 스택, 캐시, 중간 결과 저장 등에 사용되는 보조 메모리 오버헤드.
- **점유 공간(Occupied Space)**: 프로그램 실행 중 알고리즘이 실질적으로 차지하는 전체 메모리 영역.
- **상수 계수(Constant Factor)**: 입력 크기와 무관하게 동일 점근 차수 내에서 비용의 절대 크기를 결정짓는 계수.

</details>

| 복잡도 지표 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| 적용 기준 | 실시간 대화형 서비스 등 **응답시간** 단축이 최우선일 때 | 임베디드 디바이스 등 물리 **메모리 예산** 준수가 필수일 때 |
| 핵심 특징 | **기본 연산** 횟수의 점근적 증가율 | 최대 **점유 공간** 점근적 증가율 |
| 한계 | 동일 차수 내 **상수 계수** 격차 미반영 | 할당기 및 런타임 환경의 **추가 공간** 누락 |

#### 한줄 요약

- 중간 결과를 저장하면 재계산은 줄지만 그만큼 보조 메모리를 더 사용한다.

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대표 기본 연산(Representative Basic Operation)**: 전체 실행 시간 증가 추세를 대변하는 핵심 연산(루프 내 비교·대입).
- **메모리 부족(Out Of Memory, OOM)**: 시스템 물리 메모리 및 스왑 공간이 고갈되어 프로세스가 비정상 종료되는 상태.
- **벤치마크(Benchmark)**: 동일 입력 및 실행 환경에서 다수 알고리즘 후보의 실제 시간·공간 비용을 측정 및 비교하는 성능 평가.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비대표 연산 산정에 따른 병목 오판 | 지배 반복문 내 **대표 기본 연산** 기준 비용 도출 | 시간복잡도 예측 정확성 확보 |
| 평균 분석만으로 **최악 사례** 자원 초과 은폐 | 입력 분포별 평균·최악 산정 및 **자원 한도** 검증 | **OOM**·Timeout 선제 예방 |
| 재귀 스택·캐시 누락에 따른 공간 과소평가 | 최대 호출 깊이·중간 저장소를 **보조 공간** 대상 합산 | 공간복잡도 예측 정확도 향상 |
| 동일 차수 내 **상수 계수** 차이로 응답시간 역전 | 운영 환경 대상 **벤치마크** 병행 | 최적 알고리즘 후보 식별 |

#### 한줄 요약

- 병목을 좌우하는 대표 연산을 정확히 골라 최악 입력까지 자원 한도를 검증하고, 동일 차수 간 실측 벤치마크로 최종 후보를 확정한다.

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **거대 언어 모델(Large Language Model, LLM)**: 방대한 텍스트 데이터셋을 학습하여 복합 추론과 자연어 생성을 수행하는 대규모 인공지능 신경망.
- **입출력 인식 복잡도(Input/Output-Aware Complexity, IO-Aware Complexity)**: 단순 연산 횟수뿐만 아니라 프로세서와 메모리 계층 간 데이터 이동 전송 비용을 핵심 지표로 통합 분석하는 복잡도 체계.
- **그래픽 처리 장치 비디오 램(Graphics Processing Unit Video Random Access Memory, GPU VRAM)**: 그래픽 처리 장치에 직접 탑재되어 대규모 병렬 텐서 연산 데이터를 초고속으로 전송·적재하는 전용 비디오 메모리.
- **캐시 지역성(Cache Locality)**: CPU가 참조한 메모리 주소나 그 인접 주소에 단시간 내 재접근할 확률이 높은 하드웨어 친화적 참조 특성.

</details>

- 대규모 분산 데이터 처리 및 **거대 언어 모델(LLM)** 서빙 환경에서는 단순 연산 최적화를 넘어 **입출력 인식 복잡도(IO-Aware Complexity)**와 **GPU VRAM** 대역폭 병목을 극복하는 하드웨어 친화적 알고리즘으로 진화 추세.
- 이론적 점근 복잡도에만 매몰되지 않고 **캐시 지역성(Cache Locality)**, 메모리 정렬 및 런타임 상수 계수를 실측 검증하여 최적 처리량을 확보하는 아키텍처적 결단 필요.

#### 한줄 요약

- 입출력 인식 복잡도와 하드웨어 계층 구조를 반영한 시간·공간 상충 통제를 통해 초대규모 분산·인공지능 환경에 최적화된 시스템 아키텍처 확보 필요.
