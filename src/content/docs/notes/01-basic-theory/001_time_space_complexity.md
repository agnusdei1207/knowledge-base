## 미리 알고가기

- **시간·공간복잡도(Time/Space Complexity)**: 입력이 커질 때 연산량과 메모리 사용량이 얼마나 늘어나는지 나타내는 알고리즘 비용 척도
- **기본 연산**: 비교·대입처럼 실행 횟수로 시간 비용을 대표하는 연산
- **보조 공간(Auxiliary Space)**: 입력 데이터 자체를 제외하고 알고리즘이 추가로 쓰는 메모리
- **지배항(Dominant Term)**: 입력이 커질수록 전체 증가율을 결정하는 가장 빠르게 증가하는 항
- **점근 분석(Asymptotic Analysis)**: 상수와 하위항을 제외하고 큰 입력의 증가 형태를 비교하는 방법
- **계산 모델**: 기본 연산 비용을 일정하다고 가정해 하드웨어 차이를 제외하는 분석 모델
- **최선·평균·최악(Best/Average/Worst Case)**: 같은 입력 크기에서 가장 작거나 평균적이거나 가장 큰 비용을 구분하는 기준

## Ⅰ. 개요

- 정의/개념: 입력 증가에 따른 **시간·공간 증가율** 척도
- 기존 한계: 소규모 실측만으로 대규모 **자원 소진** 예측 곤란

### 쉽게 이해하기 (학습용)

- 택배 물량이 늘 때 분류 시간과 보관 공간이 얼마나 커지는지 따져 보듯, 입력 규모에 따른 연산량과 메모리 증가 형태로 풀이법의 한계를 예측한다.

## Ⅱ. 특징

- 하드웨어 차이를 배제한 **점근 증가율** 비교
- 저장과 재계산 사이의 **시간·공간 상충**
- **최선·평균·최악** 사례별 비용 범위 분리

### 쉽게 이해하기 (학습용)

- 작업자 속도는 잠시 빼고 물량이 늘어나는 모양을 비교하며, 중간 결과를 저장해 시간을 줄일 때 필요한 추가 공간도 함께 계산한다.

## Ⅲ. 아키텍처

**도표안 A — 구조도**

```mermaid
flowchart TB
    subgraph C[복잡도 분석 체계]
        direction TB
        M[계산 모델]
        T[시간 비용 분석]
        S[공간 비용 분석]
        O[점근 차수 판정]
        M -->|기본 연산 기준| T
        M -->|보조 공간 기준| S
        T -->|시간 비용 함수| O
        S -->|공간 비용 함수| O
    end
```

**도표안 B — sequenceDiagram**

```mermaid
sequenceDiagram
    participant P as 분석 절차
    participant M as 계산 모델
    participant T as 시간 비용 분석
    participant S as 공간 비용 분석
    participant O as 점근 차수 판정
    P->>M: ① 입력 규모·사례 조건
    M->>T: ② 기본 연산 기준
    M->>S: ③ 보조 공간 기준
    T-->>O: ④ 시간 비용 함수
    S-->>O: ⑤ 공간 비용 함수
    O-->>P: 지배항·점근 차수
```

| 구성요소 | 책임 |
|:---|:---|
| 계산 모델 | **기본 연산**의 단위 비용 규정 |
| 시간 비용 분석 | 입력 크기별 **기본 연산** 횟수 산정 |
| 공간 비용 분석 | 입력 크기별 최대 **보조 공간** 산정 |
| 점근 차수 판정 | **지배항**으로 증가율 분류 |

**동작 원리**

- **① 입력 규모·사례 조건**: 입력 크기와 최선·평균·최악 범위 확정
- **② 기본 연산 기준**: 지배 연산의 단위 비용과 반복 횟수 설정
- **③ 보조 공간 기준**: 호출 스택·중간 저장의 최대 점유량 설정
- **④ 시간 비용 함수**: 입력 크기별 기본 연산 횟수 표현
- **⑤ 공간 비용 함수**: 입력 크기별 최대 보조 공간 표현

> 요약: **계산 모델**의 비용을 **지배항**으로 분류

### 쉽게 이해하기 (학습용)

- 상자 한 번 옮기기를 비용 1로 정한 뒤 물량별 작업 횟수와 최대 보관 공간을 세고, 가장 빠르게 커지는 항으로 증가 등급을 매긴다.

## Ⅳ. 종류 및 비교

| 복잡도 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 적용 기준 | **응답 시간** 한도가 우선일 때 | **메모리 예산**이 우선일 때 |
| 핵심 특징 | **기본 연산** 횟수 증가율 | 최대 **점유 공간** 증가율 |
| 한계 | 같은 차수의 **상수 비용** 미반영 | 할당기·런타임 **추가 공간** 미반영 |

> 요약: **중간 결과 저장**은 시간 절약·공간 증가

### 쉽게 이해하기 (학습용)

- 중간 결과를 보관하면 같은 계산을 되풀이하지 않아 빨라지지만 저장 공간이 늘어나므로, 더 빠듯한 자원이 시간인지 메모리인지에 따라 풀이법이 달라진다.

## Ⅴ. 실무 고려사항 및 대책

| 고려사항 | 대책 | 효과 |
|:---|:---|:---|
| 대표 연산에 따른 **시간 비용** 왜곡 | 지배 반복문의 **기본 연산** 통일 | 알고리즘 간 **증가율 비교** 오차 축소 |
| 평균값의 **극단 입력** 은폐 | 평균·최악 비용 동시 산정 | **자원 한도** 초과 입력 식별 |
| 점근 차수의 **상수 비용** 누락 | 동일 차수 후보의 실측 병행 | 운영 구간의 **응답 시간** 판별 |
| 재귀·캐시의 **보조 공간** 누락 | 호출 스택·저장량 상한 포함 | 최대 **메모리 점유량** 누락 방지 |

### 쉽게 이해하기 (학습용)

- 같은 기준으로 작업 횟수를 세고 평균뿐 아니라 가장 불리한 물량도 확인하며, 호출 스택이나 캐시처럼 숨어 있는 추가 공간까지 메모리 예산에 포함한다.

## Ⅵ. 결론

- **응답·메모리 한도** 중 먼저 초과하는 자원 기준 알고리즘 선택

### 쉽게 이해하기 (학습용)

- 예상 입력에서 처리 시간과 메모리 중 먼저 한도에 닿는 자원을 찾아, 그 자원을 덜 쓰는 알고리즘을 우선 선택한다.
