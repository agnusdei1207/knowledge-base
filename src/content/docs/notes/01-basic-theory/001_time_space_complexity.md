## Ⅰ. 개요

<details><summary>용어 설명</summary>

- **알고리즘 복잡도(Algorithmic Complexity)**: 입력 크기 증가에 따른 연산량 및 메모리 증가율을 하드웨어 독립적으로 분석하는 상위 개념.
- **점근 분석(Asymptotic Analysis)**: 대규모 입력 시 지배항 중심으로 자원 소모의 점근적 한계를 평가하는 기법.
- **점근 증가율(Asymptotic Growth Rate)**: 입력 크기 증가에 따라 연산 횟수 및 메모리 점유량이 증가하는 점근적 비율.
- **자원 한도(Resource Limit)**: 서비스 수준 협약(SLA)에서 요구하는 최대 처리 시간 및 가용 메모리 임계치.

</details>

- 정의/개념: 입력 규모 변화에 따른 연산 횟수와 메모리 점유의 **점근 증가율**을 수치화한 **알고리즘 복잡도** 지표
- 배경/필요성: 실측값은 대규모 데이터 환경의 **자원 한도** 초과 및 타임아웃 예측이 불가능하여 하드웨어 독립적 **점근 분석** 체계 필수

#### 한줄 요약

- 입력 규모(N) 증가에 따른 연산 횟수 및 메모리 점유의 점근적 증가율 분석

## Ⅱ. 특징

<details><summary>용어 설명</summary>

- **지배항(Dominant Term)**: 입력이 커질수록 전체 증가율을 결정하는 가장 빠르게 증가하는 항.
- **빅오(Big-O)**: 입력 증가에 따른 비용의 점근적 상한(Asymptotic Upper Bound) 표기.
- **빅세타(Big-Theta)**: 입력 증가에 따른 비용의 정확한 점근 차수(Asymptotic Tight Bound) 표기.
- **빅오메가(Big-Omega)**: 입력 증가에 따른 비용의 점근적 하한(Asymptotic Lower Bound) 표기.
- **시간•공간 상충(Time-Space Tradeoff)**: 중간 결과를 저장해 재계산 시간을 줄이는 대신 추가 메모리를 사용하는 관계.
- **최선 사례(Best Case)**: 동일 입력 크기에서 자원 소모가 가장 적은 입력 사례.
- **평균 사례(Average Case)**: 입력 분포 확률을 반영한 기대 자원 소모(Expected Cost) 사례.
- **최악 사례(Worst Case)**: 동일 입력 크기에서 자원 소모가 가장 큰 입력 사례.

</details>

![대표 시간복잡도의 입력 크기별 증가율](/study/diagrams/complexity-growth-rates.svg)

> 입력 크기가 커질수록 붉은 O(n²)와 초록 O(n log n)이 파란 O(log n)•O(n)보다 빠르게 벌어지며, 기본 연산량을 정규화한 이론적 증가율임

- 하드웨어 독립적 **점근 증가율** 및 **빅오** 표기로 최악 시나리오 내 **자원 한도** 초과 여부 검증
- **빅세타**로 상·하한이 일치하는 정확한 점근 차수 표현 및 **빅오메가**로 비용 함수의 점근적 하한 표현
- 중간 결과 저장과 재연산 간 **시간•공간 상충**을 고려하여 메모리 여유분 기반 처리 속도 최적화 전략 수행
- 데이터 분포별 **최선 사례**·**평균 사례**·**최악 사례**를 구분하여 최적의 알고리즘 기법 선택

#### 한줄 요약

- 하드웨어 의존성 배제 및 입력 규모 변화에 따른 시간•공간 자원의 점근적 상•하한 증가율 분석

## Ⅲ. 구조 및 구성요소

<details><summary>용어 설명</summary>

- **계산 모델(Computational Model)**: 기본 연산 비용을 균일하다고 가정하여 하드웨어 차이를 배제하는 분석 모델.
- **기본 연산(Basic Operation)**: 비교·대입 등 실행 횟수로 전체 시간 비용을 대변하는 핵심 연산.
- **보조 공간(Auxiliary Space)**: 입력 데이터 자체를 제외하고 알고리즘 수행 시 추가로 요구되는 메모리.
- **점근 차수(Asymptotic Order)**: 상수와 하위항을 배제하고 지배항의 증가율을 기준으로 분류한 비용 등급.

</details>

```text
복잡도 분석 구조
├─ 계산 모델: 단위 비용 정의
├─ 시간 분석: 연산 횟수 산정
├─ 공간 분석: 추가 메모리 산정
└─ 점근 차수 판정: 증가율 분류
```

가지의 의미: 동일 계산 모델을 공유하는 정적 분석(Static Analysis) 구성 요소 집합.

| 구성요소 | 책임 |
|:---|:---|
| 계산 모델 | **기본 연산**의 단위 비용 규정 |
| 시간 분석 | 입력 크기별 **기본 연산** 수행 횟수 산정 |
| 공간 분석 | 입력 크기별 최대 **보조 공간** 산정 |
| 점근 차수 판정 | **지배항** 및 **점근 차수** 기준 증가율 분류 |

#### 한줄 요약

- 계산 모델 기반으로 단위 연산을 정의하고, 시간·공간 분석을 거쳐 점근 차수로 분류 및 평가

## Ⅳ. 흐름도

<details><summary>용어 설명</summary>

- **비용 함수(Cost Function)**: 입력 크기에 따른 시간 또는 공간 사용량의 증가 추세를 나타내는 함수.
- **상한•하한(Upper/Lower Bound)**: 입력이 극단적으로 커질 때 비용 함수가 넘지 않는 위쪽 경계 및 반드시 도달하는 아래쪽 경계.

</details>

```text
[입력 데이터 규모 (N)]
          │
          ▼
1. 계산 모델 수립 ──> 단위 기본 연산(비교/대입) 및 메모리 기준 정의
          │
          ▼
2. 시간 비용 분석 ──> 루프/재귀 호출 횟수 집계 ──> T(N) 함수 산출
          │
          ▼
3. 공간 비용 분석 ──> 고정 공간 + 가변 보조 공간(스택/버퍼) ──> S(N) 함수 산출
          │
          ▼
4. 점근 차수 판정 ──> 지배항 추출 및 Big-O/Theta 점근 차수 확정
```

**동작 원리**

1. **계산 모델 수립**: 하드웨어 의존성을 배제하기 위해 비교·대입 등 기본 연산의 단위 비용을 규정
2. **시간 비용 분석**: 입력 크기 $N$의 증가에 따른 반복문 및 재귀 호출 실행 횟수를 합산하여 시간 비용 함수 $T(N)$을 도출
3. **공간 비용 분석**: 입력 자체 메모리 외에 알고리즘 실행에 필수적인 호출 스택 및 중간 버퍼 크기를 집계하여 보조 공간 비용 함수 $S(N)$을 도출
4. **점근 차수 판정**: 도출된 비용 함수에서 상수와 저차항을 배제하고 최고차 **지배항**을 기준으로 **빅오** 및 **빅세타** 점근 차수를 확정

#### 한줄 요약

- 계산 모델 정의부터 시간·공간 비용 함수 도출, 지배항 기반의 점근 차수 판정까지 4단계로 분석을 완결

## Ⅴ. 종류 및 비교

<details><summary>용어 설명</summary>

- **시간복잡도(Time Complexity)**: 입력 크기 증가에 따른 기본 연산 횟수의 점근적 증가 정도.
- **공간복잡도(Space Complexity)**: 입력 크기 증가에 따른 최대 메모리 사용량의 점근적 증가 정도.
- **응답시간(Response Time)**: 시스템이 요청을 처리하고 결과를 반환하는 데 소요되는 시간.
- **메모리 예산(Memory Budget)**: 시스템이 알고리즘에 할당할 수 있는 최대 가용 메모리 한도.
- **추가 공간(Extra Space)**: 호출 스택, 캐시, 중간 결과 저장 등에 사용되는 보조 메모리 오버헤드.
- **점유 공간(Occupied Space)**: 프로그램 실행 중 알고리즘이 실질적으로 차지하는 전체 메모리 영역.
- **상수 계수(Constant Factor)**: 입력 크기와 무관하게 동일 점근 차수 내에서 비용의 절대 크기를 결정짓는 계수.

</details>

| 비교 항목 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| 적용 기준 | **응답시간** 확보가 서비스의 핵심일 때 | **메모리 예산** 준수가 시스템의 핵심일 때 |
| 핵심 특징 | **기본 연산** 횟수의 점근적 증가율 | 최대 **점유 공간**의 점근적 증가율 |
| 한계 및 위험 | 동일 차수 내 **상수 계수** 격차 미반영 | 할당기 및 런타임 환경의 **추가 공간** 누락 |

#### 한줄 요약

- 중간 결과의 메모이제이션은 재연산 시간을 단축하나 보조 공간 점유율을 증가시키는 상충 관계 유발

## Ⅵ. 실무 고려사항 및 대책

<details><summary>용어 설명</summary>

- **대표 기본 연산(Representative Basic Operation)**: 전체 실행 시간 증가 추세를 대변하는 핵심 연산(루프 내 비교·대입).
- **벤치마크(Benchmark)**: 동일 입력 및 실행 환경에서 다수 알고리즘 후보의 실제 시간·공간 비용을 측정 및 비교하는 성능 평가.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비대표 기본 연산 산정으로 인한 병목 지점 불일치 | 지배 반복문 내 **대표 기본 연산** 기준으로 비용 함수 도출 | 시간복잡도 예측의 정확성 확보 |
| 평균 입력 분석으로 인한 최악 사례 자원 초과 위험 은폐 | 실제 입력 분포별 평균·최악 사례 산정 및 **자원 한도** 검증 | 자원 한도 초과(OOM, Timeout) 선제 예방 |
| 재귀 스택 및 캐시 누락으로 인한 보조 공간 과소평가 | 최대 호출 깊이 및 중간 저장소 크기를 **보조 공간**에 합산 | 공간복잡도 예측 정확도 극대화 |
| 상수 계수 차이로 인한 응답시간 역전 | 운영 환경 대상 실증적 **벤치마크** 병행 | 최적 알고리즘 후보 식별 |

#### 한줄 요약

- **대표 기본 연산 선정·최악 사례 한도 검증·보조 공간 합산·실측 벤치마크 병행**

## Ⅶ. 결론

<details><summary>용어 설명</summary>

- **임계 자원 병목 판정**: 응답 지연과 가용 메모리 한계 중 서비스 중단을 유발하는 지배적 요소를 선별하여 알고리즘을 최적화하는 의사결정 체계.

</details>

- **응답시간 한도** 및 **메모리 한도** 중 선행 초과가 예상되는 자원을 기준으로 최적 알고리즘 채택

#### 한줄 요약

- 임계 자원 병목 판단 기반의 실무 최적 알고리즘 선정 체계 적용
