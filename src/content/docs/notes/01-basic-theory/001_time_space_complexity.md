## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **알고리즘 복잡도(Algorithmic Complexity)**: 입력 크기에 따른 자원 사용 증가를 분석하는 상위 개념으로, 시간복잡도와 공간복잡도로 구분함.
- **점근 분석(Asymptotic Analysis)**: 상수와 하위항을 제외하고 대규모 입력에서의 자원 증가율을 비교하는 분석 기법.
- **자원 한도(Resource Limit)**: 시스템이 허용하는 최대 처리 시간이나 메모리 사용 용량.

</details>

- 정의/개념: 입력 크기에 따른 연산량과 추가 메모리 증가율을 수치화한 **알고리즘 복잡도 지표**
- 배경/필요성: 소규모 입력 기반 측정의 대규모 입력 임계 자원 한도 사전 예측 한계 극복 필요성

#### 한줄 요약

- 입력 데이터 규모(N) 증가에 따른 연산 횟수와 메모리 점유의 점근적 증가율을 분석한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **지배항(Dominant Term)**: 입력 크기 증대 시 전체 비용 증가율을 결정하는 최우선 차수 항.
- **빅오(Big-O Notation)**: 입력 증가에 따른 비용의 점근적 상한을 나타냄.
- **빅세타(Big-Theta Notation)**: 입력 증가에 따른 비용의 정확한 점근 차수를 산정함.
- **빅오메가(Big-Omega Notation)**: 입력 증가에 따른 비용의 점근적 하한을 보증함.
- **시간•공간 상충(Time-Space Trade-off)**: 중간 결과 저장으로 재계산 시간을 단축하고 메모리 사용량을 늘리는 상호 관계를 의미함.
- **최선 사례(Best Case)**: 동일 입력 규모에서 자원 소모가 가장 적은 조건.
- **평균 사례(Average Case)**: 입력 데이터의 확률 분포를 반영한 기대 자원 소모 수준.
- **최악 사례(Worst Case)**: 동일 입력 규모에서 자원 소모가 가장 큰 한계 조건.

</details>

![대표 시간복잡도의 입력 크기별 증가율](/study/diagrams/complexity-growth-rates.svg)

> 입력 크기 증대에 따라 O(n²) 및 O(n log n)이 O(log n)·O(n) 대비 급격히 발산하는 이론적 증가율 양상

- 하드웨어 독립적인 **점근 증가율 및 Big-O** 표기법 중심 분석
- 정확 차수 및 하한 구분을 위한 **Theta·Omega** 표기법 병행
- 재계산과 중간 결과 저장 간 **시간·공간 상충** 관계 평가
- 입력 조건별 **최선·평균·최악** 비용 범위의 세분화

#### 한줄 요약

- 실행 하드웨어 의존성을 배제하고, 입력 규모 변화에 따른 시간 및 공간 자원의 점근적 상·하한 증가율을 추상화하여 비교한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **계산 모델(Computation Model)**: 단위 연산 비용의 일률적 가정을 통해 하드웨어 차이를 정률 추상화하는 분석 모델.
- **기본 연산(Basic Operation)**: 비교·대입 등 실행 횟수로 시간 비용을 대표 측정하는 연산 단위.
- **보조 공간(Auxiliary Space)**: 입력 데이터 자체 크기를 제외하고 알고리즘 수행 시 추가 할당하는 메모리 영역.
- **점근 차수(Asymptotic Order)**: 최고차 지배항의 증가율에 따라 분류한 자원 소모 비용 등급.

</details>

```text
복잡도 분석 구조
├─ 계산 모델
├─ 시간 분석기
├─ 공간 분석기
└─ 점근 차수 판정기
```

가지의 의미: 동일 계산 모델 공유 기반의 정적 분석 구성 체계

| 구성요소 | 책임 |
|:---|:---|
| 계산 모델 | **기본 연산**의 단위 비용 규정 |
| 시간 분석기 | 입력 크기별 **기본 연산** 횟수 산정 |
| 공간 분석기 | 입력 크기별 최대 **보조 공간** 산정 |
| 점근 차수 판정기 | **지배항•상하한** 기준 증가율 분류 |

#### 한줄 요약

- 계산 모델로 단위 연산을 정의하고, 시간·공간 분석기가 측정한 연산 횟수와 보조 공간을 점근 차수로 분류한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **비용 함수(Cost Function)**: 입력 규모에 따른 시간 또는 공간 사용량의 점근적 증가 추세를 수학적으로 표현함.
- **상한•하한(Upper/Lower Bound)**: 대규모 입력에서 비용 함수가 넘지 않는 위쪽 임계 경계와 도달하는 아래쪽 최소 경계.

</details>

- 시간 및 공간 비용 함수의 독립적 **점근 차수** 산정

#### 한줄 요약

- 연산 횟수와 보조 공간의 증가율을 동일한 점근 표기법으로 평가한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **시간복잡도(Time Complexity)**: 입력 크기 증가에 따른 기본 연산 횟수의 점근적 비례 관계를 수치화함.
- **공간복잡도(Space Complexity)**: 입력 크기 증가에 따른 최대 메모리 점유량의 점근적 비례 관계를 수치화함.
- **추가 공간(Additional Space)**: 입력 데이터 수용 이외에 스택, 캐시, 임시 저장 등에 추가 할당되는 자원.
- **점유 공간(Occupied Space)**: 알고리즘 실행 프로세스가 동적으로 점유하는 실질 메모리 영역.
- **할당기 비용(Allocator Cost)**: 동적 메모리의 할당, 해제 및 파편화 관리에 소요되는 부하.
- **런타임 비용(Runtime Cost)**: 가상 머신이나 프레임워크 환경이 기본 제어에 소요하는 추가 자원.
- **상수 계수(Constant Factor)**: 점근 차수가 동일하더라도 실질 실행 시간에 직접 영향을 주는 고정 상수 배율.

</details>

| 복잡도 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 적용 기준 | **시간복잡도** 감소가 응답시간을 좌우할 때 | **공간복잡도** 감소가 메모리 예산을 좌우할 때 |
| 핵심 특징 | **기본 연산** 횟수 증가율 | 최대 **점유 공간** 증가율 |
| 한계 | 같은 차수의 **상수 계수** 미반영 | 할당기•런타임 **추가 공간** 미반영 |

> 요약: 중간 결과 저장 제어를 통한 **시간·공간 상충(Trade-off)** 최적화

#### 한줄 요약

- 중간 결과를 메모이제이션하면 재연산 시간은 줄어들지만 보조 공간 점유율은 증가한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **대표 기본 연산(Representative Basic Operation)**: 전체 알고리즘 수행 시간의 점근 차수를 지배하는 루프 내 핵심 연산.
- **벤치마크(Benchmark)**: 통제된 동일 환경에서 대상 알고리즘의 시간 및 공간 자원 소모 실측치를 프로파일링하는 과정.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비대표 **기본 연산**을 세어 병목과 불일치 | 지배 반복문의 동일 기본 연산으로 **비용 함수** 산정 | 입력 증가에 따른 **시간복잡도** 예측 정확도 향상 |
| 평균 입력 분석으로 **최악 사례** 자원 초과 은폐 | 입력 분포별 **평균•최악 사례**와 자원 한도 동시 검증 | 최대 부하의 **자원 한도** 초과 방지 |
| 재귀 스택•캐시 누락으로 **보조 공간** 과소평가 | 호출 깊이와 중간 결과 저장량을 공간 비용에 포함 | 최대 **공간복잡도** 예측 정확도 향상 |
| 같은 점근 차수에서 **상수 계수** 차이로 응답시간 역전 | 목표 입력 구간의 동일 환경 **벤치마크** 병행 | 운영 구간의 우수 후보 식별 |

#### 한줄 요약

- 최악 케이스 입력에 대한 연산 횟수와 재귀 호출 스택을 포함한 보조 공간을 정밀 측정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **응답시간 한도(Response Time Limit)**: 시스템 서비스 레벨 계약(SLA)에서 규정한 최대 허용 반응 시간.
- **메모리 한도(Memory Limit)**: 알고리즘 실행 시 런타임 환경이 할당할 수 있는 최대 가용 메모리 상한.

</details>

- **응답·메모리 한도** 중 임계 자원 제약 조건을 최우선으로 고려한 알고리즘 최종 선택

#### 한줄 요약

- 임계 자원(응답시간/메모리 한도)의 병목 여부를 판단하여 최적의 시간·공간 복잡도를 가진 알고리즘을 선정한다.
