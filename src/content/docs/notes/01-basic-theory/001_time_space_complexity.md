## Ⅰ. 개요

<details>
<summary>핵심 용어</summary>

- **알고리즘 복잡도(Algorithmic Complexity)**: 입력 크기에 따른 자원 사용 증가를 분석하는 상위 개념이며 시간복잡도와 공간복잡도로 구분한다.
- **점근 분석(Asymptotic Analysis)**: 상수와 하위항을 제외하고 큰 입력의 증가 형태를 비교하는 방법이다.
- **자원 한도**: 시스템이 허용하는 최대 처리 시간이나 메모리 사용량이다.

</details>

- 정의/개념: 입력 크기에 따른 연산량과 추가 메모리 증가율을 나타내는 **알고리즘 복잡도**이다.
- 배경/필요성: 작은 입력에서 측정한 실행 시간만으로는 큰 입력에서 먼저 초과할 시간•메모리 한도를 예측하기 어렵다.

#### 한줄 요약

- 입력 데이터 규모(N) 증가에 따른 연산 횟수와 메모리 점유의 점근적 증가율을 분석한다.

## Ⅱ. 특징

<details>
<summary>핵심 용어</summary>

- **지배항(Dominant Term)**: 입력이 커질수록 전체 증가율을 결정하는 가장 빠르게 증가하는 항이다.
- **빅오(Big-O)**: 입력 증가에 따른 비용의 점근적 상한 표기이다.
- **빅세타(Big-Theta)**: 입력 증가에 따른 비용의 정확한 점근 차수 표기이다.
- **빅오메가(Big-Omega)**: 입력 증가에 따른 비용의 점근적 하한 표기이다.
- **시간•공간 상충**: 중간 결과를 저장해 재계산 시간을 줄이는 대신 메모리를 더 사용하는 관계이다.
- **최선 사례(Best Case)**: 같은 입력 크기에서 비용이 가장 작은 입력 사례이다.
- **평균 사례(Average Case)**: 입력 분포를 반영한 기대 비용 사례이다.
- **최악 사례(Worst Case)**: 같은 입력 크기에서 비용이 가장 큰 입력 사례이다.

</details>

![대표 시간복잡도의 입력 크기별 증가율](/study/diagrams/complexity-growth-rates.svg)

> 입력 크기가 커질수록 붉은 O(n²)와 초록 O(n log n)이 파란 O(log n)•O(n)보다 빠르게 벌어지며, 기본 연산량을 정규화한 이론적 증가율이다.

- 하드웨어와 무관한 **점근 증가율•Big-O** 표기가 핵심이다.
- 정확 차수•하한을 구분하는 **Theta•Omega** 표기가 핵심이다.
- 재계산과 중간 결과 저장 사이의 **시간•공간 상충** 판단이 핵심이다.
- **최선•평균•최악** 입력별 비용 범위를 분리한다.

#### 한줄 요약

- 실행 하드웨어 의존성을 배제하고, 입력 규모 변화에 따른 시간 및 공간 자원의 점근적 상·하한 증가율을 추상화하여 비교한다.

## Ⅲ. 구조 및 구성요소

<details>
<summary>핵심 용어</summary>

- **계산 모델**: 기본 연산 비용을 일정하다고 가정해 하드웨어 차이를 제외하는 분석 모델이다.
- **기본 연산**: 비교•대입처럼 실행 횟수로 시간 비용을 대표하는 연산이다.
- **보조 공간(Auxiliary Space)**: 입력 데이터 자체를 제외하고 알고리즘이 추가로 쓰는 메모리이다.
- **점근 차수**: 상수와 하위항을 제외하고 지배항의 증가율로 분류한 비용 등급이다.

</details>

```text
복잡도 분석 구조
├─ 계산 모델
├─ 시간 분석기
├─ 공간 분석기
└─ 점근 차수 판정기
```

가지의 의미: 동일 계산 모델을 공유하는 정적 분석 구성을 나타낸다.

| 구성요소 | 책임 |
|:---|:---|
| 계산 모델 | **기본 연산**의 단위 비용 규정 |
| 시간 분석기 | 입력 크기별 **기본 연산** 횟수 산정 |
| 공간 분석기 | 입력 크기별 최대 **보조 공간** 산정 |
| 점근 차수 판정기 | **지배항•상하한** 기준 증가율 분류 |

#### 한줄 요약

- 계산 모델로 단위 연산을 정의하고, 시간·공간 분석기가 측정한 연산 횟수와 보조 공간을 점근 차수로 분류한다.

## Ⅳ. 흐름도

<details>
<summary>핵심 용어</summary>

- **비용 함수**: 입력 크기에 따라 시간이나 공간 사용량이 어떻게 증가하는지 나타내는 함수이다.
- **상한•하한**: 입력이 커질 때 비용이 넘지 않는 위쪽 경계와 적어도 도달하는 아래쪽 경계이다.

</details>

- 시간•공간 비용 함수의 **점근 차수**를 각각 산정한다.

#### 한줄 요약

- 연산 횟수와 보조 공간의 증가율을 동일한 점근 표기법으로 평가한다.

## Ⅴ. 종류 및 비교

<details>
<summary>핵심 용어</summary>

- **시간복잡도(Time Complexity)**: 입력 크기에 따라 기본 연산 횟수가 증가하는 정도이다.
- **공간복잡도(Space Complexity)**: 입력 크기에 따라 최대 메모리 사용량이 증가하는 정도이다.
- **추가 공간**: 입력 자체 외에 호출 스택•캐시•중간 결과 저장에 쓰는 메모리이다.
- **점유 공간**: 실행 중 알고리즘이 실제로 차지하는 메모리 영역이다.
- **할당기 비용**: 메모리 할당•해제와 배치에 드는 공간 비용이다.
- **런타임 비용**: 프로그램 실행 환경이 추가로 사용하는 공간 비용이다.
- **상수 계수(Constant Factor)**: 입력 크기와 무관하게 같은 점근 차수의 실제 비용 크기를 바꾸는 계수이다.

</details>

| 복잡도 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 적용 기준 | **시간복잡도** 감소가 응답시간을 좌우할 때 | **공간복잡도** 감소가 메모리 예산을 좌우할 때 |
| 핵심 특징 | **기본 연산** 횟수 증가율 | 최대 **점유 공간** 증가율 |
| 한계 | 같은 차수의 **상수 계수** 미반영 | 할당기•런타임 **추가 공간** 미반영 |

> 요약: 중간 결과 저장에 따른 **시간•공간 상충**이다.

#### 한줄 요약

- 중간 결과를 메모이제이션하면 재연산 시간은 줄어들지만 보조 공간 점유율은 증가한다.

## Ⅵ. 실무 고려사항 및 대책

<details>
<summary>핵심 용어</summary>

- **대표 기본 연산**: 전체 시간 증가를 대표하는 비교•대입 등의 연산이다.
- **벤치마크(Benchmark)**: 동일한 입력과 실행 환경에서 후보의 실제 시간•공간 비용을 측정해 비교하는 시험이다.

</details>

| 문제 | 대책 | 효과 |
|:---|:---|:---|
| 비대표 **기본 연산**을 세어 실제 병목과 불일치 | 지배 반복문의 동일 기본 연산으로 **비용 함수** 산정 | 입력 증가에 따른 **시간복잡도** 예측 정확도 향상 |
| 평균 입력 분석으로 **최악 사례** 자원 초과 은폐 | 입력 분포별 **평균•최악 사례**와 자원 한도 동시 검증 | 최대 부하의 **자원 한도** 초과 방지 |
| 재귀 스택•캐시 누락으로 **보조 공간** 과소평가 | 호출 깊이와 중간 결과 저장량을 공간 비용에 포함 | 최대 **공간복잡도** 예측 정확도 향상 |
| 같은 점근 차수에서 **상수 계수** 차이로 응답시간 역전 | 목표 입력 구간의 동일 환경 **벤치마크** 병행 | 운영 구간의 우수 후보 식별 |

#### 한줄 요약

- 최악 케이스 입력에 대한 연산 횟수와 재귀 호출 스택을 포함한 보조 공간을 정밀 측정한다.

## Ⅶ. 결론

<details>
<summary>핵심 용어</summary>

- **응답시간 한도**: 서비스가 요청 결과를 반환해야 하는 최대 허용 시간이다.
- **메모리 한도**: 실행 중 알고리즘이 사용할 수 있는 최대 메모리 용량이다.

</details>

- **응답•메모리 한도** 중 먼저 초과하는 자원 기준 알고리즘을 선택한다.

#### 한줄 요약

- 임계 자원(응답시간/메모리 한도)의 병목 여부를 판단하여 최적의 시간·공간 복잡도를 가진 알고리즘을 선정한다.
