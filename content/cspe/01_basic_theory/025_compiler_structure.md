## Ⅰ. 개요
- **정의**: 고급 언어 소스 코드를 기계어 또는 중간 코드로 변환하는 번역기의 내부 단계 구조
- **배경/필요성**: 소스 언어와 목적 기계를 분리하여 전단(언어 의존)과 후단(기계 의존)을 독립적으로 교체할 수 있는 구조가 필요함
- **비유**: 외국어 책을 번역할 때 원문 해석(전단)과 자연스러운 표현 다듬기(후단)를 분리하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 전단·후단 각 단계의 역할과 입출력을 설명할 수 있는지 확인 | 6단계 파이프라인과 중간 표현(IR)의 역할 | 어휘 분석과 구문 분석의 입출력을 혼동하지 말 것 |

> 요약: 소스 코드를 전단·후단 파이프라인으로 단계별 변환하여 목적 코드를 생성하는 구조임

## Ⅱ. 구성요소
```text
  소스코드
     |
     v
  +-----------+   +-----------+   +-----------+
  | 어휘 분석  |-->| 구문 분석  |-->| 의미 분석  |  <-- 전단(Front-End)
  | (Scanner)  |   | (Parser)   |   | (Semantic) |
  +-----------+   +-----------+   +-----------+
                                       |
                                    중간 표현(IR)
                                       |
  +-----------+   +-----------+   +-----------+
  | 중간코드   |-->| 코드 최적화|-->| 코드 생성  |  <-- 후단(Back-End)
  | 생성       |   | (Optimizer)|   | (CodeGen)  |
  +-----------+   +-----------+   +-----------+
                                       |
                                       v
                                   목적 코드
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 어휘 분석기 | 소스 문자열을 토큰(식별자·키워드·연산자) 단위로 분리함 (022, 023 참조) | 문장을 단어별로 쪼개는 과정 |
| 구문 분석기 | 토큰 열을 문법 규칙에 따라 파스 트리로 구성함 (024 참조) | 단어를 문법에 맞게 문장 구조로 조립 |
| 의미 분석기 | 타입 검사·스코프 해석 등 의미적 정합성을 검증함 | 문법은 맞지만 뜻이 통하는지 확인 |
| 중간 코드 생성기 | 소스 언어·목적 기계에 독립적인 IR(3-주소 코드 등)을 생성함 | 원문과 번역문 사이의 공통 메모 |
| 코드 최적화기 | IR 수준에서 불필요 연산 제거·루프 변환 등을 수행하여 실행 효율을 높임 | 번역 초고를 다듬어 간결하게 정리 |
| 코드 생성기 | IR을 목적 기계의 명령어·레지스터 할당으로 변환하여 최종 코드를 출력함 | 정리된 원고를 인쇄 가능한 형태로 조판 |

> 요약: 전단 3단계(어휘·구문·의미)와 후단 3단계(중간코드·최적화·코드생성)로 구성됨

## Ⅲ. 절차
```text
  1.어휘분석       2.구문분석       3.의미분석/IR    4.최적화/코드생성
  (토큰화)        (파스트리)       (타입검사+IR)    (목적코드출력)
   |               |               |               |
   +---토큰열------>+---파스트리---->+---IR---------->+
  문자스트림       CFG규칙적용     스코프/타입검증   레지스터할당
```
- 1단계: 소스 문자 스트림을 정규 표현식 기반 스캐너로 토큰 열로 분리함
- 2단계: LL/LR 파서가 토큰 열을 CFG 규칙에 따라 파스 트리(AST)로 구성함
- 3단계: AST를 순회하며 타입 검사·스코프 해석을 수행하고, 3-주소 코드 등 IR을 생성함
- 4단계: IR에 최적화(상수 접기·루프 불변 코드 이동 등)를 적용한 뒤 목적 기계 코드를 생성함

> 요약: 토큰화 → 파스 트리 → IR 생성 → 최적화·코드 생성의 4단계로 소스를 번역함

## Ⅳ. 문제점
- 전단·후단 결합: IR 설계가 미흡하면 전단과 후단이 강결합되어 새 언어·기계 추가 시 전체 재작성이 필요함
- 최적화 트레이드오프: 공격적 최적화는 컴파일 시간을 증가시키고 디버깅 시 소스 매핑을 어렵게 함
- 오류 복구 품질: 구문 오류 발생 시 파서가 적절히 복구하지 못하면 연쇄 오류 메시지가 발생하여 사용성이 저하됨

> 요약: IR 결합·최적화 비용·오류 복구 품질이 컴파일러 설계의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 잘 정의된 IR(SSA 형식 등)을 중심으로 전단·후단 인터페이스를 표준화하여 결합도를 낮춤
2. 중기: 최적화 수준을 단계별(`-O0`~`-O3`)로 분리하고, 디버그 정보 보존 패스를 별도 운영함
3. 장기: 오류 복구 전략(패닉 모드·구문 삽입)을 체계화하고, 진단 메시지를 소스 위치와 정밀 매핑함

> 요약: IR 표준화 → 최적화 단계 분리 → 오류 복구 체계화로 컴파일러 품질을 향상함

## Ⅵ. 전망
- 발전 방향: LLVM 등 범용 IR 프레임워크 기반으로 다중 언어·다중 타깃 컴파일러 구축이 일반화되는 추세임
- 기술사적 판단: JIT 컴파일·AOT 컴파일 혼합 방식이 확산되며 런타임 최적화의 중요성이 증가함
- 기술사 제언: 전단·후단 분리 원칙을 준수하고, IR 수준의 분석·최적화 역량을 핵심 설계 역량으로 확보해야 함
