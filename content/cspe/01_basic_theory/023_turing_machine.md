## Ⅰ. 개요

- **정의**: 튜링 머신(Turing Machine)은 무한 테이프·읽기/쓰기 헤드·유한 상태 제어기로 구성되어 기계적으로 계산 가능한 함수의 한계를 정의하는 추상 계산 모델임.
- **배경/필요성**: 모든 수학적 명제의 참/거짓을 기계적 절차로 판정할 수 있는지를 규명하려면 "기계적 계산"이라는 직관적 개념을 수학적으로 엄밀하게 정의할 장치가 필요했으며, 유한 오토마타(상태만 보유)·푸시다운 오토마타(스택 1개 보유)로는 표현할 수 없는 임의 길이 메모리 접근을 다루기 위해 무한 테이프 모델이 도입됨.
- **출제 의도**: 7-튜플 구성요소와 전이함수 동작 이해, 유한 오토마타·푸시다운 오토마타 대비 계산 능력의 위계 파악, 정지 문제의 계산 불가능성 증명 논리, 튜링 완전성 설계 판단력을 확인함.
- **답안 방향**: 구조(7-튜플) → 동작(전이 스텝과 정지 문제) → 심화 비교(오토마타 계층 내 위치) → 실무 적용(튜링 완전성 제한 설계) 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계산 모델의 구조·한계 설명 요구 | 7-튜플 구성요소, 전이함수 동작, 정지 문제의 계산 불가능성 증명 논리 | 유한 오토마타와의 위계 차이 누락, 정지 문제를 단순 무한루프와 동일시, 튜링 완전성 근거 없는 나열 |

> 요약: 튜링 머신 답안은 유한 오토마타 대비 "무한 메모리로 얻는 계산 능력"과 그 대가인 "정지 문제의 한계"를 함께 짚어야 함.

## Ⅱ. 구조 및 구성요소

```text
무한 테이프 : ... | B | 1 | 0 | 1 | B | ...
                        ^
                        | 읽기/쓰기 헤드
                        v
                 +-------------------+
                 |  유한 상태 제어기  |
                 |   현재 상태 q      |
                 +-------------------+
                        |
                        v
         δ(q, 0) = (q', 1, R)
         -> 현재 칸에 1을 쓰고, 헤드를 오른쪽(R)으로 이동, 상태를 q'로 전이
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| `Q` (상태 집합) | 제어기가 가질 수 있는 유한한 상태 전체 | 유한 오토마타의 상태 개념을 그대로 계승 |
| `Σ` (입력 알파벳) | 입력 문자열을 구성하는 기호 집합 | 공백 기호를 제외한 유효 입력 문자 |
| `Γ` (테이프 알파벳) | 테이프에 쓸 수 있는 전체 기호 집합(공백 포함) | `Σ`보다 넓은 작업용 기호 집합 |
| `δ` (전이 함수) | (상태, 기호) → (새 상태, 쓸 기호, 이동 방향) 결정 | 매 스텝을 지배하는 규칙표 |
| `q0` / `q_accept` / `q_reject` | 시작 상태와 두 정지 상태 | 계산의 출발점과 종료 조건 |

> 요약: 튜링 머신의 5요소는 "무엇을 읽고 어떤 규칙으로 무엇을 쓰며 어디로 이동하는가"를 완전히 형식화한 최소 사양임.

## Ⅲ. 동작원리 및 흐름도

```text
[테이프 초기화] -> [현재 칸 읽기] -> [전이함수 δ 조회] -> [쓰기+이동+상태전이]
                                                                    |
                                                                    v
                                                       q_accept/q_reject 도달?
                                                          |              |
                                                        아니오            예
                                                          |              |
                                                          v              v
                                                    2단계로 복귀     정지(halt)
```

- 1단계(초기화): 입력 문자열을 테이프에 적재하고 헤드를 첫 칸에, 상태를 `q0`로 설정함.
- 2단계(판독): 헤드가 현재 칸의 기호를 읽고, 현재 상태와 함께 전이함수 `δ`를 조회함.
- 3단계(갱신): `δ`의 출력(새 상태, 쓸 기호, 이동 방향)에 따라 현재 칸에 기호를 쓰고 헤드를 이동함.
- 4단계(판정): 새 상태가 `q_accept`/`q_reject`이면 정지하고, 아니면 2단계로 복귀해 반복함. 이 반복이 유한 스텝 내에 끝나는지를 임의의 프로그램과 입력에 대해 일반적으로 사전 판정하는 알고리즘은 존재하지 않는다는 것이 정지 문제(Halting Problem)이며, 대각선 논법 기반 귀류법으로 증명됨(정지 판정기가 존재한다고 가정하면 자기 자신의 인코딩에 대해 모순되는 동작을 하는 머신을 구성할 수 있음).

> 요약: 판독-조회-갱신-판정의 4단계 반복만으로 모든 계산 가능 함수를 표현하며, 이 반복의 종료 여부 자체는 일반적으로 사전 판정 불가능함.

## Ⅳ. 특징

- 계산 능력의 최상위: 유한 오토마타(정규 언어)·푸시다운 오토마타(문맥 자유 언어)가 갖지 못한 비한정 메모리(무한 테이프)를 보유해, 촘스키 계층에서 가장 넓은 언어 집합(재귀 열거 가능 언어)을 인식함.
- 정지 문제의 계산 불가능성: 정지 여부를 항상 옳게 판정하는 일반 알고리즘은 존재하지 않으므로, 정적 분석·악성코드 탐지 도구는 완전한 자동 판정 대신 근사적 검증(제한된 루프 깊이, 타임아웃)에 의존함.
- 튜링 완전성(Turing Completeness): 어떤 계산 체계가 튜링 머신과 동일한 계산 능력을 가지면 튜링 완전이라 하며, 프로그래밍 언어·스마트 컨트랙트 설계에서 완전성을 허용할지 의도적으로 제한할지가 핵심 설계 결정 사항이 됨.
- 범용성(UTM, Universal Turing Machine): 다른 튜링 머신의 인코딩을 입력으로 받아 그대로 시뮬레이션하는 범용 튜링 머신은 "프로그램을 데이터처럼 저장·실행한다"는 개념의 이론적 원형임.

> 요약: 무한 메모리 기반의 최상위 계산 능력과, 그 대가로 따르는 정지 문제의 계산 불가능성이 튜링 머신의 핵심 특징임.

## Ⅴ. 심화 비교 및 적용 판단

| 판단 기준 | 유한 오토마타(FA) | 푸시다운 오토마타(PDA) | 튜링 머신(TM) |
|:---|:---|:---|:---|
| 메모리 구조 | 없음(상태만 보유) | 스택 1개(LIFO) | 양방향 무한 테이프 |
| 인식 언어(촘스키 계층) | 정규 언어(Type 3) | 문맥 자유 언어(Type 2) | 재귀 열거 가능 언어(Type 0) |
| 정지 여부 | 항상 유한 스텝 내 정지 | 항상 유한 스텝 내 정지 | 정지하지 않을 수 있음(정지 문제) |
| 대표 적용 | 정규표현식·렉서 | 구문 분석·파서 | 범용 프로그래밍 언어·컴퓨터 전체 |

> 요약: 메모리 형태가 없음→스택→무한 테이프로 확장될수록 인식 가능한 언어는 넓어지지만, 튜링 머신 단계에서는 그 대가로 정지 보장을 잃음.

- 참고: 시간·공간 복잡도 클래스(P, NP 등)는 튜링 머신의 자원 제한으로 정의되며, 계산 복잡도 이론은 튜링 머신을 표준 계산 모델로 삼음.

**리스크·대응 (불릿):**
- 정지 문제로 인한 완전 자동 검증 불가: 임의 프로그램의 무한루프 여부를 100% 판정하는 도구는 원리적으로 없음 → 제한된 범위의 정적 분석(bounded model checking)과 런타임 타임아웃을 병행 대응함.
- 튜링 완전 환경의 자원 고갈 공격: 무제한 반복이 가능한 실행 환경에 악의적 입력이 들어오면 서비스 거부로 이어짐 → 스마트 컨트랙트의 가스 한도, 함수 실행 타임아웃으로 대응함.

**도입 후 점검 지표 (불릿):**
- 검증 범위: 정적 분석이 커버하는 코드 경로 비율과 제한 루프 깊이 설정값으로 확인함.
- 자원 통제: 타임아웃·가스 한도 초과로 강제 종료된 실행 비율을 모니터링함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 시스템(DSL, 스마트 컨트랙트, 배치 잡)의 튜링 완전성 여부와 무한루프 위험 구간을 식별함.
2. 중기: 완전성이 불필요한 영역은 의도적으로 제한(비재귀 쿼리, 가스 한도)하고, 완전성이 필요한 영역은 타임아웃·자원 쿼터를 표준화함.
3. 장기: 근사적 정적 분석과 런타임 보호를 결합한 검증 거버넌스를 운영 정책으로 정착시킴.

- 기술사적 판단: 정지 보장이 필요한 영역은 튜링 완전성을 의도적으로 제한하고, 범용 계산이 필요한 영역은 외부 타임아웃·자원 통제로 정지 문제의 한계를 보완함.
- 기술사 제언: "정적 분석으로 모든 오류를 잡을 수 있다"는 가정은 정지 문제의 계산 불가능성에 반하므로, 근사적 검증과 런타임 방어를 병행하는 현실적 전략이 필요함.
