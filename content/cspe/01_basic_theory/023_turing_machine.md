## 미리 알고가기

- 테이프: 기호를 저장하는 무한한 칸의 열이며 추상 메모리 역할을 함
- 헤드: 현재 칸의 기호를 읽고 쓰며 좌우로 이동하는 장치임
- 상태 집합($Q$): 제어부가 가질 수 있는 유한한 내부 상태의 집합임
- 전이 함수($\delta$): 현재 상태와 기호를 다음 상태, 기록 기호, 이동 방향으로 바꾸는 규칙임
- 튜링 완전: 튜링 머신과 같은 계산 능력을 가진 언어나 시스템의 성질임
- 정지 문제: 임의의 프로그램이 멈출지 일반적으로 판정 불가능한 문제임

## 작성 근거(검토용)

- 기출 키워드이므로 정의에서 계산 가능성의 경계와 추상 기계 구성을 동시에 제시함
- 특징은 범용성·기억 능력·언어 계층·결정 불가능성을 순서대로 배치해 이론적 의의를 드러냄
- Ⅲ은 FA·PDA·TM을 비교해 튜링 머신의 차이가 단순 성능이 아니라 계산 범위임을 보이게 함
- Ⅳ와 Ⅴ는 전이 함수 한 단계가 전체 계산으로 반복되는 구조를 답안지에서 추적 가능하게 작성함
- 실무 유의점은 튜링 완전성이 보안·가용성 문제로 이어지는 지점을 제한 정책과 검증 지표로 연결함

## Ⅰ. 개요

- **정의/개념**: 튜링 머신은 유한 상태 제어부·무한 테이프·읽기·쓰기 헤드로 계산 절차를 모델링해 알고리즘으로 계산 가능한 범위를 정의하는 추상 기계임
- **배경/필요성**: 계산 가능성과 불가능성의 경계를 설명하기 위해 구현과 무관한 계산 모델이 필요함

## Ⅱ. 특징

- 읽기·쓰기·이동·상태 전이라는 단순 연산만으로 범용 계산을 표현함
- 무한 테이프를 가정해 유한 오토마타와 푸시다운 오토마타보다 큰 기억 능력을 가짐
- 재귀 열거 언어를 인식하며 범용 프로그래밍 언어의 계산 능력 기준이 됨
- 정지 문제처럼 어떤 문제는 계산 자원을 늘려도 일반 해법이 없음을 보임

## Ⅲ. 종류 및 비교

| 판단 기준 | 유한 오토마타           | 푸시다운 오토마타       | 튜링 머신               |
| :-------- | :---------------------- | :---------------------- | :---------------------- |
| 기억 장치 | 상태만 사용             | 상태와 스택 사용        | 상태와 무한 테이프 사용 |
| 헤드 동작 | 입력을 한 방향으로 읽음 | 입력을 한 방향으로 읽음 | 테이프에서 좌우 이동함  |
| 인식 언어 | 정규 언어               | 문맥 자유 언어          | 재귀 열거 언어          |
| 표현 범위 | 반복 패턴               | 중첩 구조               | 알고리즘적 계산         |
| 대표 한계 | 개수 대응 불가          | 임의 계산 불가          | 정지 문제 결정 불가     |

> 요약: 기억 장치와 이동 자유도가 커질수록 표현력은 커지지만 결정 가능성 한계도 함께 중요해짐.

## Ⅳ. 구성요소 및 구조

| 구성요소    | 설명                                                           |
| :---------- | :------------------------------------------------------------- |
| 상태 제어부 | 현재 상태를 보관하고 전이 함수에 따라 다음 동작을 선택함       |
| 테이프      | 입력, 중간값, 출력을 같은 공간에 기록하는 추상 저장소임        |
| 헤드        | 현재 칸을 읽고 새 기호를 쓴 뒤 왼쪽 또는 오른쪽으로 이동함     |
| 전이 함수   | $(q, a) \rightarrow (q', b, L/R)$ 형태로 기록 기호와 좌·우 이동을 정의함 |
| 정지 상태   | 수용 또는 거부 상태로 계산 종료와 결과 확정을 나타냄           |

```text
+----------------+
| 상태 제어부     |
+----------------+
        |
        v
... [B] [0] [1] [B] [B] ...
            ^
            |
            헤드
```

> 요약: 튜링 머신은 상태 제어부가 테이프를 읽고 쓰며 계산 단계를 진행함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 기호 읽기  | --> | 규칙 적용  | --> | 헤드 이동  | --> | 정지 확인  |
+----------+     +----------+     +----------+     +----------+
```

1. **초기화**: 입력을 테이프에 쓰고 헤드를 시작 위치에 둔 뒤 초기 상태로 설정함
2. **기호 판독**: 현재 상태와 헤드가 가리키는 기호를 전이 함수 입력으로 사용함
3. **상태 전이**: 새 기호를 기록하고 헤드를 이동하며 다음 상태로 바꿈
4. **정지 판정**: 수용·거부 상태에 도달하면 멈추고, 아니면 전이를 반복함

> 요약: 한 단계 전이 규칙을 반복해 계산을 진행하고 정지 상태에서 결과를 확정함.

## Ⅵ. 실무 적용 및 유의점

1. 템플릿 엔진이나 규칙 언어가 튜링 완전하면 사용자 입력으로 무한 루프가 가능하므로 시간 제한, 메모리 제한, 재귀 깊이 제한으로 샌드박스 정책을 검증함
2. 정적 분석은 모든 프로그램의 정지를 증명하지 못하므로 위험 루프는 제한된 언어와 타임아웃으로 통제하고 실행 추적과 미종료 작업 비율로 확인함

## Ⅶ. 결론

- 튜링 머신은 계산 가능성의 기준이므로 시스템 설계에서는 표현력을 높일수록 종료성과 자원 통제를 함께 설계해야 함
