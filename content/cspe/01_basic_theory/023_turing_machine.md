## 미리 알고가기

- 테이프: 기호를 저장하는 무한한 칸의 열이며 추상 메모리 역할을 함
- 헤드: 현재 칸의 기호를 읽고 쓰며 좌우로 이동하는 장치임
- 상태 집합($Q$): 제어부가 가질 수 있는 유한한 내부 상태의 집합임
- 전이 함수($\delta$): 현재 상태와 기호를 다음 상태, 기록 기호, 헤드 이동 방향 $L/R$로 바꾸는 규칙임
- 공백 기호($B$): 입력이 기록되지 않은 테이프 칸을 나타내는 기호임
- 유한 오토마타: 현재 상태만 기억하며 정규 언어를 인식하는 계산 모델임
- 푸시다운 오토마타: 유한 상태와 스택으로 문맥 자유 언어를 인식하는 계산 모델임
- 재귀 열거 언어: 속한 문자열은 튜링 머신이 수용하지만 속하지 않은 입력에서는 정지하지 않을 수 있는 언어임
- 튜링 완전: 튜링 머신과 같은 계산 능력을 가진 언어나 시스템의 성질임
- 정지 문제: 임의의 프로그램이 멈출지 일반적으로 판정 불가능한 문제임

## 작성 근거(검토용)

- **방향성**: 튜링 머신은 계산 가능한 문제의 상한을 정의하지만 튜링 완전한 시스템은 정지 여부를 일반적으로 판정할 수 없으므로, 실행 환경에는 처음부터 시간·메모리 자원 제한을 둬야 함
- **개요 구성**: 기출 키워드이므로 정의에서 계산 가능성의 경계와 추상 기계 구성을 동시에 제시함
- **Ⅱ. 특징 선정**: 범용성·기억 능력·언어 계층·결정 불가능성을 순서대로 배치해 이론적 의의를 드러냄
- **Ⅲ. 비교축 선정**: 처리 메커니즘, 인식 범위, 주요 한계로 FA·PDA·TM의 계산 능력을 비교하며, 세 모델은 상호 배타적 대안이 아니라 인식 범위가 포함관계로 넓어지는 계산 능력 계층이므로 적용 기준 축을 강제하지 않음
- **Ⅳ·Ⅴ. 구조·절차 선정**: 전이 함수 한 단계가 전체 계산으로 반복되는 구조를 답안지에서 추적 가능하게 작성함
- **Ⅵ·Ⅶ. 사례·결론 선정**: 튜링 완전성이 보안·가용성 문제로 이어지는 지점을 자원 제한과 검증 지표로 연결함
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 계산 가능성 경계와 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 튜링 머신은 유한 상태 제어부·무한 테이프·읽기·쓰기 헤드로 계산 절차를 모델링해 알고리즘으로 계산 가능한 범위를 정의하는 추상 기계임
- **배경/필요성**: 계산 가능성과 불가능성의 경계 설명을 위해 구현과 무관한 계산 모델이 필요함

### 쉽게 이해하기 (학습용)
- 긴 종이테이프를 옆에 두고 규칙대로 지우고 다시 쓰며 앞뒤로 움직이는 사람의 작업 방식을 추상화한 것으로, 어떤 계산이 원리적으로 가능한지 가늠하는 기준임

## Ⅱ. 특징

- 읽기·쓰기·좌우 이동·상태 전이의 네 동작을 반복해 알고리즘적 계산을 표현함
- 무한 테이프를 가정해 유한 오토마타와 푸시다운 오토마타보다 큰 기억 능력을 가짐
- 재귀 열거 언어를 인식하며 범용 프로그래밍 언어의 계산 능력 기준이 됨
- 정지 문제처럼 어떤 문제는 계산 자원을 늘려도 일반 해법이 없음을 보임

### 쉽게 이해하기 (학습용)
- 이 사람은 읽고 쓰고 옮기고 상태를 바꾸는 네 동작만 반복하지만 종이가 무한히 길어서 이전 모델보다 훨씬 많은 것을 기억할 수 있음
- 아무리 시간과 종이를 더 줘도 이 사람이 언제 작업을 끝낼지 미리 알아낼 방법은 일반적으로 없음

## Ⅲ. 종류 및 비교

| 판단 기준 | 유한 오토마타 | 푸시다운 오토마타 | 튜링 머신 |
|:---|:---|:---|:---|
| 처리 메커니즘 | 현재 상태로 입력을 단방향 처리 | 스택으로 입력을 단방향 처리 | 테이프를 읽고 쓰며 양방향 이동 |
| 인식 범위 | 정규 언어 | 문맥 자유 언어 | 재귀 열거 언어 |
| 주요 한계 | 같은 수의 기호 대응 불가 | 범용 계산 표현 불가 | 일반 정지 여부 판정 불가 |

> 요약: 기억 구조가 확장될수록 인식 범위가 넓어지지만 임의 프로그램의 정지 여부는 일반적으로 판정할 수 없음.

### 쉽게 이해하기 (학습용)
- 유한 오토마타는 지금 서 있는 자리만 기억하며 한 방향으로 걷는 사람, 푸시다운 오토마타는 거기에 바구니를 든 사람, 튜링 머신은 종이테이프를 들고 앞뒤로 오가며 지우고 쓰는 사람임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 상태 제어부 | 현재 상태 저장·다음 동작 선택 |
| 테이프 | 입력·중간값·출력의 추상 저장소 |
| 헤드 | 기호 읽기·쓰기·좌우 이동 |
| 전이 함수 | $(q, a) \rightarrow (q', b, L/R)$ 상태·기호·이동 규칙 |
| 정지 상태 | 수용·거부 결과를 확정하는 종료 상태 |

```text
+----------------+
| 상태 제어부     |
+----------------+
        |
        v
... [B] [0] [1] [B] [B] ...
            ^
            |
            헤드
```

> 요약: 튜링 머신은 전이 함수로 테이프 읽기와 쓰기를 반복하고 정지 상태에서 결과를 확정함.

### 쉽게 이해하기 (학습용)
- 상태 제어부는 지금 무슨 일을 하고 있는지 기억하는 머릿속, 테이프는 작업하는 종이, 헤드는 손, 전이 함수는 다음에 뭘 할지 정하는 규칙표, 정지 상태는 작업을 마쳤다는 신호임

## Ⅴ. 원리 및 절차 흐름도

```text
현재 상태·헤드 위치 확인 → 테이프 기호 판독 → 전이 규칙 적용
                                           ├─ 계속 상태 → 쓰기·헤드 이동 후 반복
                                           └─ 정지 상태 → 수용·거부 결과 확정
```

1. **초기화**: 입력을 테이프에 쓰고 헤드를 시작 위치에 둔 뒤 초기 상태로 설정함
2. **기호 판독**: 현재 상태와 헤드가 가리키는 기호를 전이 함수 입력으로 사용함
3. **상태 전이**: 새 기호를 기록하고 헤드를 이동하며 다음 상태로 바꿈
4. **정지 판정**: 수용·거부 상태에 도달하면 멈추고, 아니면 전이를 반복함

> 요약: 한 단계 전이 규칙을 반복해 계산을 진행하고 정지 상태에서 결과를 확정함.

### 쉽게 이해하기 (학습용)
- 종이 준비하고 시작 위치에 손을 올린 뒤, 지금 칸의 글자를 읽고 규칙표대로 쓰고 옮기기를 반복하다가, 정해진 완료 표시가 나오면 멈춤

## Ⅵ. 실무 사례

1. 규칙 실행 플랫폼은 튜링 완전 스크립트에 실행 시간과 메모리 한도를 적용함
2. 정적 분석 도구는 종료 조건이 없는 반복 경로를 찾아 검토 대상으로 표시함

### 쉽게 이해하기 (학습용)
- 사용자가 올린 자동화 스크립트가 무한히 도는 것을 막기 위해 실행 시간과 메모리에 미리 제한을 걸어두는 것과 같음

## Ⅶ. 결론

- 튜링 머신은 알고리즘으로 계산 가능한 범위를 정의하며, 튜링 완전한 시스템은 종료를 항상 보장할 수 없어 자원을 제한해야 함
- 사용자 스크립트·규칙 엔진은 샌드박스와 시간·메모리 한도를 기본으로 두고, 종료 여부를 정적 분석만으로 보장하려 하지 말아야 함

### 쉽게 이해하기 (학습용)
- 무엇이든 계산할 수 있는 만능 규칙을 허용하는 대신, 그 규칙이 언제 멈출지는 보장 못 하므로 실행 환경에 울타리와 시간제한을 미리 쳐둬야 함
