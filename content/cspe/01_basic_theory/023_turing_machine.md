## 미리 알고가기

- 테이프(Tape): 한 칸씩 나뉜 채 좌우로 무한히 이어지는 저장 공간 모델임. 끝없이 긴 종이 띠 위에 칸마다 기호를 적었다 지웠다 하는 모습을 떠올리면 됨
- 헤드(Head): 테이프 위를 한 칸씩 움직이며 기호를 읽고 쓰는 장치임. 타자기 헤드가 한 글자씩 찍으며 옆으로 이동하는 모습과 비슷함
- 상태 전이(State Transition): 현재 상태와 지금 읽은 기호의 조합만 보고 다음에 무엇을 쓰고 어느 방향으로 이동하며 어떤 상태로 바뀔지 정하는 규칙임
- 결정 가능성(Decidability): 어떤 문제든 유한한 시간 안에 예/아니오 답을 내놓는 알고리즘이 실제로 존재하는지를 가리키는 성질임
- 유한 오토마타(FA, Finite Automaton): 테이프나 별도 저장 공간 없이 상태만으로 입력을 처리하는 가장 단순한 계산 모델임. 자판기가 지금까지 넣은 동전 상태만 기억한 채 다음 버튼 입력을 받는 것과 비슷함
- 푸시다운 오토마타(PDA, Pushdown Automaton): 상태에 스택 하나를 더한 모델이며, 접시를 쌓고 맨 위 것부터만 꺼내듯 가장 최근 것부터 되짚어야 하는 문제에 적합함

## Ⅰ. 개요

- **정의/개념**: 튜링 머신은 유한한 상태를 갖는 제어기와 좌우로 무한히 늘어나는 테이프, 그 테이프를 한 칸씩 읽고 쓰며 움직이는 헤드로 이루어진 계산 모델이며, 어떤 문제가 알고리즘으로 풀리는지를 판정하는 기준선 역할을 함
- **배경/필요성**: 특정 프로그래밍 언어나 하드웨어에 매이지 않고 "이 문제는 정해진 절차로 풀 수 있는가"라는 질문에 답하려면 보편적인 계산 기준 모델이 필요했고, 튜링 머신은 상태와 테이프라는 최소 구성만으로 이 기준을 정의함

## Ⅱ. 특징

- 범용성: 상태 전이 규칙만으로 조건 분기, 반복, 메모리 갱신까지 모두 표현할 수 있어 특정 하드웨어나 언어에 의존하지 않는 범용 계산 모델이 됨
- 최소 구성: 상태, 기호, 전이 규칙이라는 극히 단순한 구성 요소만으로 현대 컴퓨터가 수행하는 계산의 본질을 설명할 수 있음. 복잡한 요리도 결국 자르기, 익히기, 섞기 같은 몇 가지 동작의 조합으로 설명되는 것과 비슷함
- 판정 기준 제공: 어떤 문제가 결정 가능성을 갖춰 유한 시간 안에 항상 답을 내는지, 아니면 원칙적으로 답을 낼 수 없는 계산 불가능 문제인지 가르는 이론적 경계선을 제공함
- 속도보다 경계: 튜링 머신은 한 칸씩만 이동하는 방식이라 실제 하드웨어보다 훨씬 비효율적이지만, "계산 가능한가"라는 질문에 대해서는 지금까지 알려진 가장 강력한 기준으로 남아 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 유한 오토마타(FA) | 푸시다운 오토마타(PDA) | 튜링 머신 |
|:---|:---|:---|:---|
| 기억 구조 | 상태만 기억하고 별도 저장 공간이 없음 | 상태에 스택 하나를 추가로 씀 | 상태에 더해 무한히 늘어나는 테이프를 자유롭게 읽고 씀 |
| 표현력 | 정규 언어(반복·선택 패턴만으로 표현되는 언어)까지 처리함 | 문맥 자유 언어(괄호 짝처럼 중첩 구조가 있는 언어)까지 처리함 | 재귀 열거 가능 언어(원칙적으로 어떤 절차로도 인식 가능한 언어)까지 처리함 |
| 대표 한계 | 몇 칸 전에 나온 값을 기억해 비교하는 장거리 의존 검사를 못함 | 스택 맨 위가 아닌 중간 위치를 임의로 수정하지 못함 | 표현력 자체의 한계는 없지만 정지 여부처럼 계산 자체가 불가능한 문제가 남음 |
| 의미 | 문자열이 특정 패턴에 맞는지 인식함 | 문자열의 중첩 구조(구문)가 올바른지 인식함 | 절차로 풀 수 있는 모든 문제를 원칙적으로 계산함 |

> 요약: 기억 구조가 늘어날수록 표현력이 커지지만, 튜링 머신에 이르러도 결정 불가능한 문제 자체는 사라지지 않음.

## Ⅳ. 구성요소 및 구조

- 상태 집합(State Set, Q): 유한 개의 제어 상태 목록이며, 시작 상태에서 출발해 계산이 끝나면 수리 상태(Accept State) 또는 거부 상태(Reject State)로 도착함
- 테이프와 헤드: 미리 알고가기에서 본 테이프와 헤드가 실제 저장·이동 장치 역할을 하며, 헤드는 현재 칸의 기호만 읽고 쓸 수 있어 한 번에 한 칸씩만 정보를 갱신함
- 전이함수(Transition Function, δ): 현재 상태와 지금 읽은 기호의 조합을 입력받아 쓸 기호, 이동 방향, 다음 상태 세 가지를 출력하는 규칙표이며, 이 표 하나가 튜링 머신의 모든 동작을 결정함
- 정지 상태(Halt State): 수리 또는 거부 상태에 도달하는 순간 헤드 이동과 전이가 멈추는 지점이며, Ⅲ에서 본 표현력의 상한과 별개로 결정 가능성 여부는 결국 이 지점에 도달하는지로 판가름남

```text
+-------------------+        +---------------------+
| 상태 집합(Q)        | -----> | 전이함수(δ) 규칙표    |
| 현재 상태 저장       |        | (기호,방향,다음상태)  |
+-------------------+        +----------+-----------+
                                         |
                                         v
                             +------------------------+
                             | 헤드가 테이프 기호를      |
                             | 읽고 쓰고 한 칸 이동함    |
                             +-----------+------------+
                                         |
                                         v
                                +------------------+
                                | 정지 상태 도달 시  |
                                | 결과 확정         |
                                +------------------+
```

> 요약: 전이함수 하나가 상태·테이프·헤드를 연결해 계산을 진행시키고, 정지 상태 도달 여부가 결과 확정 시점을 정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
| 상태/헤드  | -> | 기호 읽기  | -> | 전이함수   | -> | 쓰기+이동  | -> | 정지 판정  |
| 초기화    |    |           |    | 적용      |    | +상태전이  |    |           |
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
```

1. **상태/헤드 초기화**: 시작 상태를 지정하고 헤드를 테이프의 정해진 첫 칸에 둠
2. **기호 읽기**: 헤드가 현재 칸에 적힌 기호를 읽음
3. **전이함수 적용**: 현재 상태와 읽은 기호 조합으로 쓸 기호, 이동 방향, 다음 상태를 정함
4. **쓰기 및 상태 전이**: 헤드가 기호를 쓰고 방향대로 한 칸 이동한 뒤 상태를 바꾸며, 정지 상태가 아니면 2단계로 돌아가 반복함
5. **정지 판정**: 수리 상태나 거부 상태에 도달하면 계산을 멈추고 결과를 확정하며, 어느 정지 상태에도 도달하지 못한 채 2~4단계가 무한히 반복되면 그 입력은 정지문제(Halting Problem)가 말하는 결정 불가능 사례가 됨

## Ⅵ. 실무 적용 및 유의점

1. 정적 분석 도구나 빌드 파이프라인의 무한 루프 탐지기를 설계할 때는 임의의 프로그램이 멈추는지를 항상 미리 판정할 수는 없다는 정지문제의 한계를 전제해야 하므로, 실제 도구는 반복 횟수 상한과 타임아웃, 루프 불변식 검사 같은 근사 규칙으로 대체하고 오탐률과 미탐률로 판정 정확도를 확인함
2. 설정 파일 언어나 템플릿 엔진을 만들 때 조건문·반복문까지 허용해 튜링 완전(Turing Complete)하게 설계할지, 반복 없는 선언적 문법으로 제한할지를 먼저 정해야 하며, 튜링 완전하게 설계하면 사용자 입력만으로 무한 루프나 과도한 자원 점유가 발생할 수 있으므로 실행 시간 상한과 호출 깊이 제한을 걸고 타임아웃 발생 빈도와 최대 메모리 사용량으로 안전성을 확인함

## Ⅶ. 결론

튜링 머신은 상태·테이프·전이함수라는 최소 구성으로 표현력의 상한을 정의하지만 정지문제처럼 결정 불가능한 영역은 그 상한 안에서도 사라지지 않으므로, 실무에서는 언어나 시스템에 어느 수준의 계산 능력을 허용할지를 판단 기준으로 삼아야 함.
