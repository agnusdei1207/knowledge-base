# 튜링 머신 (Turing Machine)

## 1. 개요

- **정의/개념**: 튜링 머신은 무한 테이프, 읽기/쓰기 헤드, 상태 전이 규칙으로 계산 과정을 모델링하는 추상 계산 모델이다.
- **배경/필요성**: 알고리즘으로 계산 가능한 것과 불가능한 것을 엄밀히 구분하려면 특정 하드웨어나 언어에 의존하지 않는 일반 계산 모델이 필요하다.

튜링 머신은 실제 컴퓨터 설계도가 아니라 계산 가능성, 결정 가능성, 정지 문제를 설명하는 기준 모델이다.

## 2. 특징 및 비교

| 구분 | 유한 오토마타 | Pushdown Automata | 튜링 머신 |
|---|---|---|---|
| 저장 구조 | 유한 상태 | 스택 | 무한 테이프 |
| 표현 범위 | 정규 언어 | 문맥 자유 언어 | 계산 가능한 언어 |
| 핵심 역할 | 패턴 인식 | 구문 인식 | 일반 계산 모델 |
| 한계 설명 | 중첩 표현 한계 | 임의 계산 한계 | 정지 문제 등 결정 불가 |

튜링 머신은 표현력이 가장 크지만, 모든 문제가 해결 가능하다는 뜻은 아니다. 핵심 판단은 계산 가능성과 효율 가능성을 구분하는 것이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Tape | 기호를 읽고 쓰는 저장 공간 | 무한 확장 가정 |
| Head | 현재 셀을 읽고 쓰며 좌우 이동 | 순차적 조작 |
| State | 계산 중 내부 상태 | 전이 기준 |
| Transition Function | 상태와 기호에 따른 쓰기·이동·다음 상태 | 계산 절차 |
| Halt State | 계산 종료 상태 | 수용, 거부, 정지 |

```text
----------+      +----------+      +----------+      +----------+
| 현재상태 | ---> | 기호읽기 | ---> | 쓰기/이동 | ---> | 다음상태 |
+----------+      +----------+      +----------+      +----------+
                                                     |
                                                     v
                                                정지여부 판단
```

이 흐름은 프로그램 실행을 추상화한 것이므로, 튜링 머신의 문제점은 계산을 수행하는 절차보다 어떤 입력에서 정지 여부를 알 수 있는지로 이어진다.

## 4. 문제점 및 개선방안

1. **계산 가능성과 효율성 혼동**
   - 튜링 계산 가능하다는 사실이 다항 시간 해결 가능성을 의미하지 않는다.
   - **개선방안**: 계산 가능성, 결정 가능성, 시간복잡도 계층을 분리해 설명한다.

2. **정지 문제 오해**
   - 모든 프로그램의 정지 여부를 일반 알고리즘으로 판정할 수 없다.
   - **개선방안**: 제한된 언어, 정적 분석 규칙, 타임아웃, 검증 가능 범위를 명확히 한다.

3. **실무 적용 과잉 일반화**
   - 추상 모델을 실제 성능 모델처럼 사용하면 운영 판단과 맞지 않는다.
   - **개선방안**: 이론적 한계 설명에는 튜링 머신을, 성능 판단에는 복잡도와 측정 지표를 사용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 계산 이론 교육 | 계산 가능성과 정지 문제 설명 | 개념 구분 정확도 |
| 프로그램 분석 | 완전 판정 불가 영역을 제한된 규칙으로 분석 | 오탐·미탐, 분석 시간 |
| 보안 검증 | 악성 코드 행위 분석에서 정지·도달성 한계 고려 | 검증 범위, 타임아웃 |

## 6. 결론

튜링 머신은 알고리즘의 계산 가능성과 한계를 설명하는 기준 모델이다. 구성요소와 동작 절차를 먼저 잡고, 정지 문제를 통해 "계산 모델이 강해도 모든 판단을 자동화할 수는 없다"는 결론으로 이어진다.
