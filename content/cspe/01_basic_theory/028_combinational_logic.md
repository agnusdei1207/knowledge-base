# 📖 【암기용】 개념 완전 이해

> 목적: 조합 논리 회로를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **조합 논리 회로**는 현재 들어온 입력값만으로 즉시 출력값이 결정되는 '기억력 없는' 논리 회로다. (가산기, 멀티플렉서, 디코더 등)
- **왜 필요한가**: 컴퓨터의 두뇌인 ALU(산술논리장치)에서 덧셈을 하거나, 메모리의 수많은 주소 중 딱 한 곳을 찾아가는 등 '연산과 선택'을 수행하는 일꾼이 필요하기 때문이다.
- **핵심 직관**: 커피 자판기의 '계산기'와 같다. 지금 누른 버튼(입력)에 맞춰 바로 커피(출력)가 나온다. 방금 전에 누가 무슨 버튼을 눌렀는지(과거)는 전혀 신경 쓰지 않는다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 반가산기 (Half Adder, HA) | 두 비트를 더해 합(Sum)과 자리올림(Carry)을 냄 | 일의 자리 숫자 두 개 더하기 |
| 전가산기 (Full Adder, FA) | 아랫자리에서 올라온 자리올림(Carry In)까지 합쳐 3비트 덧셈 | 십의 자리 덧셈 (아랫자리 올림 포함) |
| 멀티플렉서 (Multiplexer, MUX) | 여러 입력 중 하나를 선택해 출력으로 내보냄 ($2^n \rightarrow 1$) | 기차 선로 전환기 (여러 길 중 하나 선택) |
| 디코더 (Decoder) | 압축된 입력(n비트)을 풀어서 여러 신호($2^n$) 중 하나를 켬 | 비밀번호 누르면 특정 사물함 딱 하나 열림 |

## 깊이 이해
- **배경·문제의식**: 논리 게이트(AND, OR, NOT) 한두 개로는 쓸모있는 일을 할 수 없다. 덧셈을 하려면 여러 게이트를 조합해야 하는데, 이를 모듈(부품) 단위로 규격화한 것이 조합 논리 회로다.
- **작동 원리 (반가산기와 전가산기)**: 
  - 반가산기: A, B 두 비트를 더할 때 1+1=2(2진수로 10)가 된다. 일의 자리(Sum)는 A 다르고 B 다를 때 1이 되는 **XOR 게이트**로, 자리올림(Carry)은 둘 다 1일 때만 1이 되는 **AND 게이트**로 만든다.
  - 전가산기: 반가산기 2개와 OR 게이트 1개를 조합하여, 밑에서 올라온 캐리(Cin)까지 3개의 값을 완벽하게 더한다. 이 전가산기를 수십 개 이어 붙이면 32비트 덧셈기가 된다(Ripple Carry Adder).
- **비유 (멀티플렉서 MUX)**: 4대의 TV 카메라가 있고 방송국 화면은 1개다. 감독이 선택 스위치(선택선) 2개를 조작(`00`이면 1번, `11`이면 4번)해서 단 하나의 화면만 송출하는 장치가 MUX다. 반대는 디먹스(DEMUX)다.
- **구체 예시**: 
  - $3 \times 8$ 디코더: 3비트(`101`, 즉 5)를 입력하면 8개의 출력선 중 5번 선 딱 하나만 전기가 들어온다. 메모리 주소 해석에 쓰인다.
- **흔한 오해·주의점**: 가산기는 "값을 저장"하지 않는다. 전기를 끊으면 계산 결과는 바로 날아간다. 값을 유지하려면 순서 논리 회로(레지스터)가 추가로 필요하다.

## 연결 개념
- 논리 게이트 — 조합 회로를 만드는 기본 재료
- 순서 논리 회로 (플립플롭) — 조합 회로에 '기억력'을 더한 것
- 병렬 가산기 (Carry Lookahead Adder) — 자리올림 지연을 없앤 고속 가산기

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 조합 논리 회로(Combinational Logic)는 피드백 루프나 기억 소자 없이, 현재의 입력값 조합만으로 출력이 100% 결정되는 논리 게이트들의 집합이다.
> 2. **가치**: 반가산기/전가산기는 ALU의 산술 연산을 담당하고, 멀티플렉서/디코더는 데이터 버스와 메모리 주소 선택을 통제하여 CPU 데이터 패스(Datapath)를 구성한다.
> 3. **판단 포인트**: 다수의 전가산기를 직렬 연결할 때 발생하는 자리올림 전파 지연(Ripple Carry Delay)을 해결하기 위해 CLA(Carry Lookahead Adder) 적용 여부를 통제해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기억 소자(플립플롭) 유무에 따른 회로 분류 인식 | 현재 입력에만 의존, 피드백 루프 없음, 지연(Delay)만 존재 | "상태(State)를 유지한다"는 순서 논리와 혼동 서술 |
| 대표 조합 회로의 논리 구조와 역할 매핑 | HA/FA(가산기), MUX(데이터 선택), 디코더(주소 해독) | 디코더($n \rightarrow 2^n$)와 MUX($2^n \rightarrow 1$) 역할 혼동 |
| 가산기의 성능 병목 원인 및 해결책 인지 | 리플 캐리 가산기(RCA)의 지연 원리, 올림수 예측 가산기(CLA) | 하드웨어적 병목(지연 시간 증가) 해결책 누락 |

> 요약: 조합 회로의 무기억성(Memory-less) 정의를 못 박고, 가산기와 데이터 선택기(MUX/디코더)가 CPU 아키텍처에 어떻게 배치되는지 연결해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 내부 상태나 기억 능력이 없으며, 오직 현재 인가된 입력 신호의 조합만으로 즉시 출력 신호가 생성되는 논리 회로
- 배경: CPU 내부에서 복잡한 수치 연산을 수행하고 데이터 경로를 통제하려면, 게이트들을 모듈화한 표준화된 연산 및 선택 블록이 필요
- 필요성: 연산(Adder), 선택(MUX), 해독(Decoder)을 조합 회로로 분리·블록화하여, 프로세서 설계의 복잡도를 낮추고 재사용성을 극대화

---

## Ⅱ. 구조 및 구성요소

```text
조합 논리 회로 기반 CPU Datapath 핵심 구조
명령어 주소 -> [디코더] -> 제어 신호
데이터 버스 -> [멀티플렉서 (MUX)] -> [전가산기 (ALU)] -> 연산 결과 (순간적 출력)
```

| 회로 모듈 | 구성 및 특징 | CPU 내 주요 역할 |
|:---|:---|:---|
| 전가산기 (Full Adder) | HA 2개 + OR 게이트 1개 ($A, B, C_{in} \rightarrow Sum, C_{out}$) | ALU의 덧셈/뺄셈 기본 단위 연산기 |
| 멀티플렉서 (MUX) | $2^n$개 입력, $n$개 선택선, 1개 출력 | 여러 레지스터 중 하나를 선택해 버스로 송출 |
| 디코더 (Decoder) | $n$개 입력, $2^n$개 출력 | $N$비트 주소를 해독해 특정 메모리 셀 1개 활성화 |
| 인코더 (Encoder) | $2^n$개 입력, $n$개 출력 | 인터럽트 우선순위 압축(Priority Encoder) |

> 요약: 가산기는 데이터를 가공하고, MUX와 디코더는 데이터가 갈 길을 열어주는 트래픽 컨트롤러 역할을 한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
전가산기(FA)의 다중 비트 확장 흐름 (리플 캐리 가산기 기준)
LSB 입력(A0, B0) -> LSB 연산(S0, C1 발생) -> C1 전파 -> 상위 비트(A1, B1, C1) 연산 -> MSB 도달
```

- 1단계 [입력 및 하위 연산]: 첫 번째 반가산기에서 입력 $A$와 $B$를 XOR 하여 부분합(Sum) 생성, AND 하여 부분 캐리 생성
- 2단계 [상위 캐리 누적]: 두 번째 반가산기에서 하위에서 올라온 $C_{in}$과 부분합을 다시 더해 최종 $Sum$ 확정
- 3단계 [캐리 아웃 발생]: 두 반가산기에서 발생한 캐리를 OR 연산하여 최종 $C_{out}$을 다음 비트로 전파
- 4단계 [선택선 제어(MUX/Decoder)]: MUX는 선택선(Select) 비트 조합을 AND 배열로 필터링하여 단 1개의 입력만 출력선으로 통과시킴

> 요약: 조합 회로의 모든 동작은 클럭(Clock) 동기화 없이, 입력 전압이 게이트들을 통과해 출력으로 도달하기까지의 물리적 지연(Propagation Delay)만으로 흐른다.

---

## Ⅳ. 특징

- 무기억성(Memory-less): 피드백(출력이 입력으로 돌아옴) 루프가 없어 과거의 상태를 전혀 알지 못함 (오직 상태 기계의 연산부로만 기능)
- 시간 독립성: 클럭 신호(Edge/Level)에 맞춰 동작하는 것이 아니라, 입력이 변하면 게이트 지연(Gate Delay) 직후 곧바로 출력이 연속적으로 변함
- 설계 직관성: 요구사항을 진리표(Truth Table)로 100% 나열할 수 있어, 카르노 맵(K-Map)을 통한 수학적 최소화 설계가 완벽히 보장됨

> 요약: 상태가 없으므로 설계가 수학적으로 투명하지만, 반대로 데이터를 '저장'하기 위해서는 반드시 순서 논리 회로와 결합해야 한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 조합 논리 회로 (Combinational) | 순서 논리 회로 (Sequential) | 선택 기준 |
|:---|:---|:---|:---|
| 출력 결정 요인 | 현재 입력만 | 현재 입력 + 과거 상태 | 연산인가 저장인가 |
| 필수 구성 요소 | 게이트 (AND, OR, NOT) | 게이트 + 기억 소자 (Flip-Flop) | 상태 보존 필요성 |
| 적용 아키텍처 | ALU, 디코더, 인코더, MUX | 레지스터, 카운터, 메모리 | 데이터 가공 vs 보관 |

> 요약: 연산을 처리하는 조합 회로와 그 결과를 다음 클럭까지 쥐고 있는 순서 회로가 결합되어야 비로소 상태 머신(컴퓨터)이 완성된다.

**리스크·대응 (기본 불릿):**
- 리플 캐리 지연(Ripple Carry Delay): N비트 가산 시 최하위 비트의 캐리가 MSB까지 전파되는 데 $O(N)$의 게이트 지연 발생 → 대응: 캐리 예측 로직을 병렬로 구성하여 지연을 $O(1)$로 줄이는 CLA(Carry Lookahead Adder) 적용 (지표: 덧셈기 임계 경로 지연 시간)
- 디코더 활성화 충돌: 메모리 뱅크 선택 시 글리치(Glitch)로 인해 다수 셀이 동시 활성화될 위험 → 대응: 디코더 출력단에 Enable(EN) 핀을 두어, 주소 버스 전압이 완전히 안정화된 후만 활성화 (지표: 다중 활성화 에러율 0)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU 파이프라인 데이터 패스 최적화: ALU 덧셈기를 CLA 기반으로 병렬 설계하여, 한 클럭 사이클 내에(EX 단계) 32비트/64비트 연산이 완료되도록 임계 경로(Critical Path) 단축
2. FPGA 라우팅 자원 설계: MUX(멀티플렉서) 트리를 대량으로 배치하여, 사용자가 프로그래밍하는 논리에 따라 데이터 흐름과 논리 셀 간의 연결 스위치를 동적으로 재구성 (LUT 기반 로직)
3. 주소 해독 및 칩 선택(Chip Select): 메모리 컨트롤러에 디코더를 배치하여 32비트 주소 중 상위 비트로는 메모리 뱅크를, 하위 비트로는 행/열을 즉시 찾아내어 읽기/쓰기 활성화

**결론 (2줄):**
- 기술사 판단: 조합 논리 회로는 진리표를 물리적 실체로 바꾼 논리의 심장이며, 특히 다중 비트 연산 시 캐리 지연(CLA 적용) 통제가 전체 시스템 클럭 속도를 좌우한다.
- 향후 방향: 최근 병렬 처리 요구 증가로 인해, 복잡한 조합 로직을 전통적 회로 대신 딥러닝 텐서(Tensor) 연산에 특화된 MAC(Multiply-Accumulate) 조합 유닛으로 초집적화하는 추세다.
