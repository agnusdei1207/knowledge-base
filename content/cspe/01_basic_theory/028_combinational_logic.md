# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **조합 논리 회로(Combinational Logic Circuit)**는 출력이 오직 **현재 입력**에만 의존하고 **이전 상태(메모리)를 갖지 않는** 디지털 논리 회로다.
- **왜 필요한가**: 027에서 다룬 AND·OR·NOT·XOR 같은 기본 게이트는 하나만으로는 참/거짓 판정 이상을 못 한다. 이 게이트들을 정해진 배선 규칙으로 엮으면 덧셈, 데이터 선택 같은 실용적인 "기능 단위 회로"가 만들어지는데, 그 결과물이 조합 논리 회로다.
- **핵심 직관**: 커피 자판기 동전 투입구다. 500원을 넣으면 즉시 500원어치 회로가 켜지고, 동전을 빼면 즉시 꺼진다. 어제 500원을 넣었다는 상태를 기억하지 못한다 — 오직 지금 이 순간의 입력에만 정직하게 반응한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 조합 논리 회로 | 출력이 오직 현재 입력에만 의존, 상태 저장 없음 — 이 글의 **상위 핵심 키워드** | 자판기 — 넣은 순간에만 반응 |
| 순서(순차) 논리 회로 (대조 개념) | 현재 입력 + 이전 상태(메모리)까지 반영 (029에서 상세) | 어제 층수를 기억하는 엘리베이터 |
| 반가산기 (Half Adder) | 입력 A, B 2개로 합(Sum)·자리올림(Carry) 계산, Cin 없음 | 한 자리만 더하는 계산기 |
| 전가산기 (Full Adder) | 입력 A, B, Cin 3개로 Sum·Cout 계산 (다수결 함수) | 이전 자리 캐리를 이어받는 계산기 |
| 리플 캐리 가산기 (Ripple Carry Adder) | 전가산기 n개를 직렬 연결해 n비트 덧셈 수행 | 도미노 — 캐리가 순서대로 넘어감 |
| 캐리 전파 지연 (Carry Propagation Delay) | 자리수 n에 비례해 늘어나는 지연시간 | 앞사람부터 순서대로 통과해야 하는 줄 |
| 캐리 예측 가산기 (Carry Look-ahead Adder) | 캐리를 미리 병렬 계산해 지연을 줄인 개선형 | 줄을 안 서고 한 번에 계산 |
| 멀티플렉서 (Multiplexer, MUX) | 선택선(Select Line) n개로 2ⁿ개 입력 중 하나를 골라 출력 | 채널 여러 개 중 하나를 고르는 리모컨 |
| 디멀티플렉서 (Demultiplexer, DEMUX) | MUX의 반대 — 입력 1개를 2ⁿ개 출력 중 하나로 분배 | 우체국 소포 분류기 |
| 디코더 (Decoder) | n비트 코드로 2ⁿ개 출력선 중 정확히 하나만 활성화 | 주소 번호로 방 하나 찾아 불 켜기 |
| 인코더 (Encoder) | 디코더의 반대 — 2ⁿ개 입력 중 켜진 것을 n비트 코드로 압축 | 켜진 스위치 위치를 번호로 요약 |

## 깊이 이해

### 조합 논리 회로란 무엇이고 왜 등장했나 (027과의 연결)
- 027에서 다룬 기본 게이트(AND·OR·NOT·XOR)는 낱개로는 단순 판정만 할 뿐, 덧셈 같은 실용 기능을 못 만든다. 이 게이트들을 특정 규칙으로 조합해 "입력을 넣으면 원하는 출력이 나오는" 기능 블록으로 승격시킨 것이 조합 논리 회로다.
- 정의적 특징은 "출력이 오직 현재 입력에만 의존"한다는 것 — 내부에 상태를 담는 소자(플립플롭)도 없고, 출력이 다시 입력으로 되먹임되는 피드백 루프도 없다. 그래서 같은 입력을 넣으면 언제나 같은 출력이 나온다(순수 함수와 유사). 이것이 029에서 다룰 순서 논리 회로(이전 상태를 저장·반영)와 갈라지는 핵심 지점이다.

### 반가산기(Half Adder) — 두 비트를 더하는 최소 단위
- 입력 A, B 두 개로 합(Sum)과 자리올림(Carry)을 계산한다. Sum = A XOR B, Carry = A AND B.
- 진리표: (A,B)=(0,0)→S0,C0 / (0,1)→S1,C0 / (1,0)→S1,C0 / (1,1)→S0,C1.
- **왜 XOR가 합인가**: 이진수 덧셈에서 1+1=10이므로, 두 입력이 같으면(0+0 또는 1+1) 합 자리는 0이 되고, 다르면(0+1 또는 1+0) 합 자리는 1이 된다. XOR는 정확히 "입력이 서로 다를 때만 1"을 내는 게이트이므로 이 규칙과 정확히 일치한다.
- **한계**: 반가산기는 입력이 2개뿐이라 이전 자리에서 넘어온 캐리를 받을 입력 핀이 없다. 그래서 여러 자리를 연속으로 더하는 다중 비트 덧셈에는 그대로 쓸 수 없다 — 이 한계를 없앤 것이 전가산기다.

### 전가산기(Full Adder) — 이전 자리 캐리까지 받는다
- 입력 3개(A, B, Cin)로 Sum과 Cout을 계산한다. Sum = A XOR B XOR Cin, Cout = AB + Cin(A XOR B).
- **Cout 수식은 다수결(majority) 함수다** — A, B, Cin 세 입력 중 2개 이상이 1이면 Cout=1이다. 검증: A=1,B=1,Cin=0 → AB=1이므로 Cout=1 (1이 2개). A=1,B=0,Cin=1 → AB=0, Cin·(A XOR B)=1·1=1이므로 Cout=1 (1이 2개). A=1,B=1,Cin=1 → AB=1, 나머지 항은 0이지만 이미 1이므로 Cout=1 (1이 3개). A=1,B=0,Cin=0 → AB=0, Cin·(...)=0이므로 Cout=0 (1이 1개뿐). 즉 "1의 개수가 2개 이상"일 때만 캐리가 발생한다는 규칙과 정확히 맞아떨어진다.
- 전가산기 1개는 반가산기 2개 + OR 게이트 1개로 구현할 수 있다: 1단계로 A·B를 반가산해 중간 합 S1과 캐리 C1을 얻고, 2단계로 S1·Cin을 다시 반가산해 최종 Sum과 캐리 C2를 얻은 뒤, Cout = C1 OR C2로 합친다.

### 리플 캐리 가산기(Ripple Carry Adder) — 워크드 예제
- 전가산기 n개를 자리마다 직렬로 연결해 n비트 이진 덧셈을 수행하는 회로다. 자리 i의 Cout이 곧바로 자리 i+1의 Cin으로 연결된다.
- **문제**: 최상위 자리의 결과가 확정되려면 캐리가 최하위 자리부터 순서대로 "물결처럼(ripple)" 전파되어야 한다. 이 지연을 캐리 전파 지연(Carry Propagation Delay)이라 하며, 지연시간이 비트 수 n에 비례해 늘어난다(전가산기 1개의 지연 × n). 32비트, 64비트로 자리수가 늘수록 이 지연이 병목이 되므로, 캐리를 미리 부울 수식으로 병렬 계산해 지연을 O(log n) 수준으로 줄인 캐리 예측 가산기(Carry Look-ahead Adder)가 등장한 배경이 여기에 있다.
- **워크드 예제 — 4비트 0101(5) + 0011(3)을 자리별로 손으로 추적**:
  - bit0(LSB): A=1, B=1, Cin=0 → Sum = 1⊕1⊕0 = 0, Cout = AB + Cin(A⊕B) = (1·1) + 0·(1⊕1) = 1 + 0 = 1
  - bit1: A=0, B=1, Cin=1(=bit0의 Cout) → Sum = 0⊕1⊕1 = 0, Cout = (0·1) + 1·(0⊕1) = 0 + 1 = 1
  - bit2: A=1, B=0, Cin=1(=bit1의 Cout) → Sum = 1⊕0⊕1 = 0, Cout = (1·0) + 1·(1⊕0) = 0 + 1 = 1
  - bit3(MSB): A=0, B=0, Cin=1(=bit2의 Cout) → Sum = 0⊕0⊕1 = 1, Cout = (0·0) + 1·(0⊕0) = 0 + 0 = 0
  - 결과: S3S2S1S0 = 1000 = 8. **검산**: 5 + 3 = 8, 일치.
  - 여기서 bit1의 계산은 bit0의 Cout(=1)이 나올 때까지 시작할 수 없고, bit2·bit3도 마찬가지로 앞자리 결과를 기다린다 — 이것이 캐리가 순차적으로 "리플(ripple)"되며 전파되는 구조이며, 자리수가 늘수록 이 대기시간이 누적되는 이유다.

### 멀티플렉서(MUX)·디먹스·디코더·인코더 — 데이터 선택과 라우팅
- **멀티플렉서(Multiplexer, MUX)**: n개의 선택선(Select Line)으로 2ⁿ개의 입력 중 하나를 골라 단일 출력선으로 내보내는 "데이터 선택기"다. 예: 4:1 MUX는 선택선 2개(S1S0)로 입력 4개(I0~I3) 중 하나를 선택한다 — S1S0=00이면 I0, 01이면 I1, 10이면 I2, 11이면 I3이 출력으로 나간다.
- **디멀티플렉서(Demultiplexer, DEMUX)**: MUX의 정반대 동작이다. 입력 1개를 받아 선택선 값에 따라 2ⁿ개의 출력 중 하나로만 분배한다.
- **디코더(Decoder)**: n비트 입력 코드를 받아 2ⁿ개의 출력선 중 정확히 하나만 활성화(1로 켬)한다 — 예: 2비트 메모리 주소를 받아 4개 메모리 뱅크 중 해당하는 하나만 활성화하는 용도.
- **인코더(Encoder)**: 디코더의 반대 동작이다. 2ⁿ개의 입력선 중 켜진(1인) 하나를 찾아 n비트 코드로 압축해 출력한다.

## 연결 개념
- 027 논리 게이트·부울 대수 (조합 논리 회로를 조립하는 기본 벽돌 — AND/OR/NOT/XOR)
- 029 순서(순차) 논리 회로 (조합 논리에 상태 저장 소자를 더한 것 — 이 파일과의 핵심 대조 개념)
- ALU (산술 논리 연산 장치 — 가산기 등 조합 논리 회로의 복합체)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 내부 기억 소자(Memory)와 출력 피드백(Feedback) 루프 없이, 오직 현재 인가된 입력 신호에 의해서만 출력이 즉각 산출되는 Stateless 디지털 논리 회로다.
> 2. **가치**: 반가산기/전가산기 병합을 통해 CPU ALU 코어를 구축하고, 멀티플렉서/디코더를 융합하여 메모리 주소 라우팅을 초고속으로 수행하는 연산 계층 인프라다.
> 3. **판단 포인트**: 과거 상태를 기억할 수 없으므로, 게이트 단수 누적으로 인한 캐리 전파 지연(Ripple Carry Delay)을 캐리 예측(Look-ahead) 회로로 $O(1)$ 단축시키는 H/W 설계가 성능을 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 조합 논리 회로 물리 구조와 한계 파악 | 무상태 메모리 부재, 현재 입력 100% 종속 즉각 연산 | 과거 이전 상태 영향을 받는다고 쓰면 즉시 0점 (순서 논리와 오독) |
| 주요 응용 소자의 기능/구조 차별화 | 반가산기(XOR+AND), 전가산기(Cin 확장), MUX 기전 | H/W 논리 게이트 조합 구조식 도출 없이 소자명만 나열 기술 |

> 요약: 조합 논리 회로는 복잡한 계산을 와이어 스피드(Wire-speed)로 쳐내지만 기억력은 0인 연산기이며, 클럭 주기 내에 얼마나 빨리 신호를 통과시키느냐가 칩셋 수율을 100% 결정한다.

## Ⅰ. 개요 및 필요성

- 정의: 과거 입출력 상태와 완전 무관하게, 특정 시점에 인가된 입력 신호의 부울 논리 조합(AND, OR, NOT) 결과만으로 출력이 동기 확정되는 무상태 논리 회로
- 배경: 단일 트랜지스터 수준을 넘어 덧셈, 뺄셈, 메모리 주소 해독 등 CPU 인스트럭션을 실질 수행할 하드웨어 패키징 단위 요구
- 필요성: 시스템 클럭 홀딩(Holding) 개입 없이 신호 인가 즉시(비동기) 산술 연산을 확정 짓고, 데이터 버스 라우팅(MUX)을 초고속 처리하기 위해 필수

## Ⅱ. 핵심 소자(1) - 산술 연산 매커니즘 (가산기)

```text
[반가산기 HA] 입력 A, B -> XOR 게이트(합 S), AND 게이트(캐리 C) 추출 
[전가산기 FA] 하위 올림수(Cin) 포함 3비트(A,B,Cin) 합산 -> 멀티비트 직렬 가산기 구축 토대 맵핑
```

| 소자 구분 | 논리 연산 부울 수식 | 아키텍처 제약 및 활용 |
|:---|:---|:---|
| 반가산기 (Half Adder) | $S = A \oplus B$, $C = A \cdot B$ | 밑자리 캐리(Carry-in) 수용 핀이 없어 연속 덧셈 확장 불능 |
| 전가산기 (Full Adder) | 반가산기 2개 + OR 게이트 1개 직결 | 3비트 입력 인가 수용으로 N개 캐스케이딩(Cascading) 연결하여 32비트 ALU 덧셈 코어 즉각 확장 가능 |

> 요약: 가산기의 가치는 단순 덧셈을 넘어, 이 입력단에 NOT(1의보수)을 달고 Carry-in에 1을 밀어 넣는 2의 보수 체계를 인가하여 감산기(뺄셈기) 없이 감산을 100% 퉁치는 데 있다.

## Ⅲ. 핵심 소자(2) - 버스 라우팅 및 변환 흐름도

```text
[MUX] 4개 입력 라인 -> [선택선 2비트 제어] -> 1개 출력 라인 압축 $4 \rightarrow 1$ (데이터 스위칭)
[Decoder] 2비트 주소 입력 -> [해독기 통과] -> 4개 물리 메모리 뱅크 중 단 1곳만 Enable 전압 인가 $2 \rightarrow 4$
```

| 소자 구분 | H/W 처리 논리 역할 | 실무 아키텍처 매핑 |
|:---:|:---|:---|
| 멀티플렉서 (MUX) | $2^n$ 개 입력 데이터 선 중 선택 핀($n$개) 신호로 1가닥 출력선 연결 | 병렬 데이터 덩어리를 단일 통신선으로 직렬화 밀어넣는 시분할 다중화 라우터 |
| 디멀티플렉서 (DEMUX) | 1가닥 입력을 $2^n$ 개 출력 선 중 한 곳으로 정밀 분배 스위칭 | 단일 통신 스트림을 받아 CPU 내부 여러 캐시 레지스터 뱅크에 동시 분배 |
| 디코더 (Decoder) | $n$ 비트 이진 코드를 최대 $2^n$ 개 고유 출력선 활성화로 1:N 복호화 | CPU 0x1A 가상 메모리 주소를 입력받아 램(RAM) 칩셋 물리 행(Row) 특정 위치 전압 활성화 |
| 인코더 (Encoder) | $2^n$ 신호 중 하나가 켜지면 $n$ 비트 이진 주소 코드로 N:1 압축 | 100키 키보드 물리 스위치 누름 신호를 ASCII 코드 7비트로 압축해 인터럽트 전송 |

> 요약: 멀티플렉서가 데이터를 원하는 길목으로 보내는 "철로 변경 스위치"라면, 디코더는 압축된 이진 평문을 물리적 메모리 좌표로 해독하는 "번역 네비게이션"이다.

## Ⅳ. 특징 (가산기 구현 방식 비교)

| 구분 | 리플 캐리 가산기 (RCA) | 캐리 예측 가산기 (CLA) | 판단 포인트 |
|:---|:---|:---|:---|
| 캐리 전파 방식 | 하위 비트 캐리가 상위 비트로 순차 전달 | 부울 수식으로 캐리를 사전에 병렬 계산 | 지연 시간을 결정하는 핵심 요인 |
| 지연 특성 | 비트 폭 $N$에 비례한 $O(N)$ 게이트 지연 | $O(\log N)$ 수준으로 지연 단축 | 클럭 목표 주파수와 직결 |
| 게이트/면적 비용 | 전가산기 $N$개 직렬 연결, 면적 최소 | 캐리 생성/전파 로직 추가로 면적 증가 | 저전력·저비용 설계는 RCA 유지 |
| 적용 사례 | 저비용 임베디드 8~16비트 ALU | 고성능 CPU 32/64비트 정수 연산 코어 | 비트 폭이 클수록 CLA 이득 확대 |

> 요약: 조합 논리 회로 자체는 상태가 없어 구조가 단순하지만, 동일한 가산 기능도 캐리 전파 구현 방식에 따라 지연·면적 트레이드오프가 갈린다.

## Ⅴ. 심화 비교 판단 (조합 논리 vs 순서 논리 회로)

| 비교 축 | 조합 논리 회로 (Combinational) | 순서 논리 회로 (Sequential) | 아키텍처 시스템 판단 기준 |
|:---|:---|:---|:---|
| 결과 산출 근거 | **오직 현재 핀 입력 신호** | 현재 입력 + **과거 피드백 저장 상태** | 무상태 연산기 vs 상태 제어기(State Machine) |
| 기억 소자(Memory) | **절대 없음** | **플립플롭(F/F), 래치 등 보유** | 버퍼 캐시 유지 필요 여부 |
| 피드백 루프 | 출력이 입력으로 궤환 반환되지 않음 | 출력선이 물리적으로 꺾여 입력단 피드백 | 발진(Oscillation) 및 제어 논리 사이클 구성 |
| 실무 대표 모듈 | ALU 반가산기, 멀티플렉서, 디코더 | CPU 레지스터, SRAM, 카운터 제어 유닛 | 실행 유닛(Execution) vs 컨트롤 유닛(Control) |

> 요약: 컴퓨터는 조합 논리(계산 근육)만 있으면 방금 계산 결과를 망각한다. 이 옆에 순서 논리(플립플롭 해마)를 달아 계산 결과를 담아줘야 진정한 폰 노이만 아키텍처가 잉태된다.

| 리스크 | 발생 원인 | 대응 기법 (H/W 아키텍처 스위칭) | 확인 지표 |
|:---|:---|:---|:---|
| 정적 해저드(Static Hazard) 글리치 | 동일 입력 신호가 게이트마다 다른 경로 지연을 거쳐 도착하여, 출력이 정착 전 순간적으로 오값을 통과시킴 | 여분 게이트(Consensus Term) 추가 또는 클럭 샘플링 시점을 지연해 정착 후 값만 래치 | 글리치 지속 시간 대비 클럭 주기 여유(Timing Margin) |
| 팬아웃(Fan-out) 과부하 | 디코더/MUX 출력선 1개가 과다한 후단 게이트 입력을 동시 구동하여 전파 지연 증가 | 버퍼 트리(Buffer Tree) 삽입, 팬아웃 한계치 내 게이트 재배치 | 출력단 구동 게이트 수, 전파 지연 증가율 |

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 범용 CPU ALU 코어 파이프라인 설계: 복잡한 64비트 산술 명령어를 $O(1)$ 1클럭 사이클 내 확정짓기 위해, 전가산기 병렬 레이아웃과 CLA 예측기 결합 조합 논리 매트릭스로 정수 연산 블록 원칩 집적화 수행
2. 대용량 스토리지/캐시 메모리 어드레싱 인프라: 캐시 컨트롤러에서 수백만 개 트랜지스터 뱅크 고속 타겟팅을 위해 64비트 주소 디코더를 캐스케이딩(Cascading) 배열하고 MUX 데이터 버스 인출 정밀 추출 로직 전개
3. L4/L7 네트워크 스위치 시분할 다중화 파이프라인: 스위치 물리 계층에서 64개 다중 포트 이더넷 유입 프레임을 대용량 64:1 멀티플렉서 회로에 인가하여 단일 400Gbps 백본 광통신 직렬 링크로 초고속 맵핑 전송

**결론 (2줄):**
- 기술사 판단: 조합 논리 회로는 메모리 개입 없이 순수 하드웨어 스위치 전파 지연만으로 출력이 확정되는 Stateless 연산의 정점이며, ALU 연산 속도 임계치를 결정짓는 뿌리다.
- 향후 방향: 최근 AI NPU 신경망 칩셋 설계에서는 곱셈기/가산기 조합 회로를 수만 개 병렬 타일 구조로 엮어낸 시스톨릭 어레이(Systolic Array) 형태로 행렬 텐서 연산을 하드웨어 극한으로 가속 중이다.
