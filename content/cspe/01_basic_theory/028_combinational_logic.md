# 📖 【암기용】 개념 완전 이해

> 목적: 조합 논리 회로를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 현재 입력값만으로 출력이 결정되는 디지털 논리 회로
- **왜 필요한가**: ALU, 주소 선택, 데이터 경로 제어처럼 즉시 계산해야 하는 기능은 저장 상태 없이 입력 조합으로 결정된다.
- **핵심 직관**: 조합 논리는 "기억하지 않는 계산기"이며, 입력이 바뀌면 게이트 지연 후 출력이 바뀐다.

## 깊이 이해
- **배경·문제의식**: CPU 데이터 경로에는 덧셈, 비교, 선택, 인코딩 같은 순간 판단이 많음
- **처리 방식**: 이 기능은 클럭을 기다리는 저장소가 아니라 게이트 연결로 처리함
- **작동 원리**: 진리표에서 출력 조건을 도출하고, AND/OR/NOT 또는 NAND/NOR 게이트로 구현함
- **대표 회로**: 반가산기, 전가산기, 디코더, 인코더, 멀티플렉서임
- **비유**: 자동판매기에서 현재 누른 버튼 번호에 따라 배출구가 정해지는 동작과 같음
- **무상태 특성**: 이전 버튼 기록은 출력에 영향을 주지 않음
- **구체 예시**: 1비트 전가산기는 A, B, Cin 입력으로 `Sum=A⊕B⊕Cin`, `Cout=AB + Cin(A⊕B)`를 만든다.
- **흔한 오해·주의점**: 조합 회로에도 지연이 있음
- **위험 요인**: 저장 상태는 없지만 게이트 전파 지연 때문에 hazard와 glitch가 발생할 수 있음

## 연결 개념
- 논리 게이트·부울 대수 — 조합 회로의 수식 기반
- 순서 논리 회로 — 조합 회로 출력에 레지스터를 붙여 상태 저장
- ALU — 가산기·MUX·논리 연산기의 통합 구조


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 조합 논리 회로는 현재 입력의 논리 조합만으로 출력이 결정되는 무상태 회로이다.
> 2. **가치**: 가산기, 멀티플렉서, 디코더를 통해 CPU ALU와 데이터 경로의 즉시 연산을 구현한다.
> 3. **판단 포인트**: 기능 진리표, 게이트 단계 지연, fan-in/fan-out, glitch 제거 여부를 함께 검토해야 한다.


## Ⅰ. 개요 및 필요성

- 개요: 조합 논리 회로는 기억 요소 없이 입력 조합으로 출력을 산출함
- 배경: 프로세서와 디지털 장비는 덧셈, 선택, 비교, 디코딩을 클럭 사이클 안에서 완료해야 함
- 필요성: 진리표 기반 설계와 전파 지연 분석이 회로 품질을 좌우함


## Ⅱ. 구조 및 구성요소

```text
입력 벡터 -> 조합 게이트 -> 출력 벡터
조합 게이트
  / 가산기
  / MUX
  / 디코더
  / 비교기
```

| 구성요소 | 역할 | 대표 수식·규모 |
|:---|:---|:---|
| 가산기(Adder) | 산술 덧셈 수행 | 1비트 FA, n비트 RCA |
| 멀티플렉서(MUX) | 선택 신호로 입력 1개 전달 | `2^k:1` MUX, 선택 k비트 |
| 디코더(Decoder) | k비트 입력을 `2^k`개 출력으로 변환 | 주소 선택, 명령 해석 |
| 비교기(Comparator) | 두 입력의 대소·동등 판단 | `A=B`, `A>B` |

> 요약: 조합 논리는 가산·선택·해석·비교 회로로 구성되며, 모두 현재 입력만 출력에 반영한다.


## Ⅲ. 동작원리 및 흐름도

```text
요구 기능 -> 입력 변수 선정 -> 진리표 작성 -> 논리식 도출
-> 게이트 연결 -> 지연·glitch 검토 -> 출력 확정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입출력 변수와 비트 폭 결정 | n비트 입력, m비트 출력 명시 |
| 2 | 진리표 또는 수식 작성 | 입력 조합 `2^n` 기준 |
| 3 | 게이트 회로 구현 | AND/OR/NOT, XOR, MUX 사용 |
| 4 | 전파 지연과 hazard 검토 | critical path, static hazard 확인 |

> 요약: 조합 회로는 기능 명세를 진리표로 고정한 뒤 게이트 구현과 지연 검토로 출력 신뢰성을 확보한다.


## Ⅳ. 특징

| 구분 | 조합 논리 회로 | 순서 논리 회로 | 판단 포인트 |
|:---|:---|:---|:---|
| 출력 의존성 | 현재 입력 | 현재 입력 + 과거 상태 | 저장 요소 존재 여부 |
| 시간 기준 | 전파 지연 | 클럭 엣지·setup/hold | 타이밍 분석 방식 |
| 대표 회로 | Adder, MUX, Decoder | Flip-Flop, Counter, Register | 데이터 경로 vs 상태 제어 |
| 위험 요소 | glitch, static/dynamic hazard | metastability, race | 동기화 필요성 |

> 요약: 조합 논리는 무상태 즉시 계산에 적합하나, 게이트 전파 지연과 glitch를 타이밍 제약 안에서 관리해야 한다.


## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 순서 논리 | 조합 논리 | 현재 입력만으로 출력 결정 시 |
| 비용/성능 | ripple 구조 | carry-lookahead·carry-select | 32비트 이상 지연 제약 존재 |
| 운영/위험 | 기능 검증 위주 | hazard·glitch·STA 검토 | critical path와 fan-out 기준 |

> 요약: 조합 논리는 저장 상태가 없을 때 선택하며, 지연과 glitch를 동시에 검증해야 함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 지연 초과 | carry chain·MUX depth 증가 | CLA, 파이프라인 분할 | worst negative slack |
| glitch | 입력 도착 시간 차이 | hazard-free 구현, 레지스터링 | glitch pulse width |
| fan-out 초과 | 단일 신호 다중 부하 | 버퍼 삽입, 로직 복제 | fan-out count |

> 요약: 조합 회로 리스크는 지연, glitch, fan-out이며 STA와 파형 검증으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 기능 | 진리표·assertion 100% 통과 | 시뮬레이션 |
| 타이밍 | 목표 클럭에서 slack 0ns 이상 | STA |
| 자원 | 게이트 수·LUT 수 예산 이내 | 합성 리포트 |

> 요약: 조합 논리 적용 효과는 기능 통과율, slack, 자원 사용량으로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ALU 설계: 32비트 ripple-carry adder는 carry chain 32단, 지연 제약이 있으면 carry-lookahead 구조 선택
2. 데이터 경로 선택: 4:1 MUX는 선택선 2비트, 파이프라인 stage별 입력 소스 명시
3. 검증: SystemVerilog assertion으로 `sel=2'b10 -> out=in2` 같은 MUX 속성 검증

**결론 (2줄):**
- 기술사 판단: 면적 제약이면 ripple 구조, 클럭 주파수 제약이면 carry-lookahead 또는 carry-select 구조를 선택함
- 향후 방향: 고집적 SoC는 논리 합성 후 STA(Static Timing Analysis)와 formal equivalence 검증을 필수 절차로 둠
