# 조합 논리 회로 - 가산기·멀티플렉서 (Combinational Logic)

## 미리 알고가기

- **게이트(gate)**: AND, OR, NOT, XOR처럼 입력 신호 몇 개를 받아 0/1 한 개를 내는 가장 작은 논리 부품. 이것들을 레고처럼 이어 붙여 회로를 만든다.
- **전파 지연(propagation delay)**: 입력이 바뀐 순간부터 출력이 올바른 값으로 자리 잡을 때까지 걸리는 시간. 게이트 하나를 통과할 때마다 조금씩 쌓인다.
- **캐리(carry)**: 덧셈에서 한 자리가 넘쳐 윗자리로 올려 보내는 값. 우리가 손으로 `7+8`을 계산할 때 1을 올려 적는 그 "받아올림"이다.

## 1. 개요

- **정의/개념**: 조합 논리 회로는 지금 들어온 입력 값만으로 출력이 곧바로 결정되는 회로다. 어제 무슨 값이 들어왔는지, 방금 전 상태가 무엇이었는지는 하나도 기억하지 않고, 오직 현재 입력을 게이트로 계산해 답을 낸다.
- **배경/필요성**: 디지털 회로가 하는 일은 크게 둘로 나뉜다. 하나는 "두 수를 더해라", "여러 입력 중 하나를 골라라"처럼 지금 값만 보면 답이 정해지는 계산이고, 다른 하나는 "몇 번 눌렸는지 세라"처럼 과거를 기억해야 하는 일이다. 뒤엣것은 상태를 저장할 메모리와 클럭이 필요해 복잡하지만, 앞엣것에까지 굳이 메모리를 달면 회로만 무거워진다. 그래서 기억이 필요 없는 계산은 게이트만 엮어 입력이 들어오는 즉시 출력을 뽑는 조합 논리로 만든다. 다만 게이트를 여러 겹 통과하는 동안 지연이 쌓이고 신호가 순간적으로 흔들리므로, 이 두 가지를 다스리는 것이 조합 논리 설계의 숙제로 남는다.

## 2. 특징 및 비교

디지털 회로를 이해하는 첫 갈림길은 "출력이 무엇으로 정해지는가"다. 조합 논리는 현재 입력만 보고, 순서 논리는 현재 입력에 더해 지금까지 쌓아 온 상태까지 본다.

| 구분 | 조합 논리 | 순서 논리 |
|:---|:---|:---|
| 출력을 정하는 것 | 현재 입력만 | 현재 입력 + 이전 상태 |
| 기억 장치 | 없음 | 플립플롭·레지스터로 상태 저장 |
| 시간의 기준 | 게이트 전파 지연 | 클럭에 맞춰 상태 전이 |
| 대표 회로 | 가산기, 멀티플렉서, 디코더 | 카운터, 유한상태기계(FSM) |
| 무엇을 검증하나 | 진리표가 맞는지, 지연이 규격 안인지 | 타이밍이 맞는지, 원하는 상태에 도달하는지 |

> 요약: 지금 입력만으로 답이 나오면 조합 논리, 과거를 기억해야 하면 순서 논리다.

같은 입력을 넣으면 조합 논리는 언제나 같은 출력을 낸다. 이 성질 덕분에 회로가 맞는지는 "가능한 모든 입력 조합에 대해 원하는 출력이 나오는가"를 적은 진리표 하나로 완전히 따질 수 있다. 그래서 설계의 판단 기준도 기능이 진리표대로 정확한가, 게이트 수는 적은가, 전파 지연이 규격 안에 드는가, 한 게이트가 감당할 입출력 부담(fan-in/fan-out)이 넘치지 않는가로 좁혀진다.

## 3. 구성요소/구조

조합 논리 회로는 입력 신호가 게이트망을 통과해 출력으로 나오는 한 방향 파이프라인이고, 그 통과 시간이 곧 전파 지연이다.

```text
+----------+      +--------------+      +----------+
| 입력신호 | ---> |   게이트망   | ---> | 출력신호 |
|  A, B... |      | AND OR XOR.. |      |  Y, C... |
+----------+      +--------------+      +----------+
                  통과하는 동안 지연 누적
```

| 구성요소 | 하는 일 | 왜 중요한가 |
|:---|:---|:---|
| 입력 신호 | 회로에 들어오는 현재 값 | 과거 값이 아니라 지금 값만 계산에 쓰임 |
| 논리 게이트 | AND·OR·NOT·XOR로 판단을 수행 | 이것들의 조합이 곧 기능 |
| 불 함수(Boolean function) | 출력을 입력의 논리식으로 적은 명세 | 무엇을 만들지 정하는 설계도 |
| 전파 지연 | 입력 변화가 출력에 반영되는 시간 | 회로가 낼 수 있는 최고 속도의 한계 |
| 출력 신호 | 계산이 끝난 결과 값 | 클럭을 기다리지 않고 즉시 나옴 |

> 요약: 입력을 불 함수대로 게이트에 흘려 출력을 내되, 그 통과 시간(전파 지연)이 속도를 좌우한다.

대표 회로 둘도 결국 이 틀 안에 있다. **가산기**는 한 자리 덧셈을 XOR로 합(`A XOR B`)을, AND로 받아올림(`A AND B`)을 계산하는 반가산기에서 출발한다. 여기에 아랫자리에서 올라온 캐리까지 받는 전가산기를 여러 개 이어 붙이면 여러 자리 덧셈기가 된다. **멀티플렉서(MUX)**는 여러 입력선 중 하나를 골라 내보내는 스위치인데, 선택 신호가 "몇 번 입력을 통과시킬지"를 정하는 회전식 다이얼 역할을 한다. 둘 다 기억 없이 입력만으로 출력이 정해지므로 조합 논리로 깔끔하게 표현된다.

## 4. 문제점 및 개선방안

1. **전파 지연이 쌓여 속도를 갉아먹음**: 게이트를 여러 겹 통과할수록 지연이 층층이 더해지는데, 특히 가산기는 아랫자리 캐리가 정해져야 윗자리를 더할 수 있어 캐리가 자리 수만큼 줄줄이 기다리는 지연(리플 캐리)이 생긴다.
   - **개선방안**: 논리식을 단순화해 게이트 단수를 줄이고, 캐리를 미리 병렬로 계산하는 캐리 예측(carry lookahead) 구조로 바꾼다. (확인: 최장 경로 전파 지연, 최대 동작 주파수)

2. **입력이 바뀌는 순간 잘못된 값이 번쩍임(해저드/글리치)**: 여러 경로를 지나온 신호가 미세한 지연 차이로 어긋나게 도착하면, 최종 값이 자리 잡기 직전 짧게 엉뚱한 0/1이 튀어나온다.
   - **개선방안**: 카르노맵에서 서로 인접한 항을 덮는 여유항(consensus term)을 추가해 흔들리는 경로를 메우고, 순서 논리로 넘길 때는 클럭 가장자리에서만 값을 읽어 흔들림 구간을 피한다. (확인: 글리치 발생 여부, 셋업/홀드 위반 건수)

3. **입력 조합을 빠뜨려 예외에서 오동작**: 진리표의 일부 조합을 설계에서 빠뜨리면 그 입력이 실제로 들어왔을 때 정의되지 않은 엉뚱한 값을 낸다.
   - **개선방안**: 가능한 모든 입력 조합을 진리표로 빠짐없이 채우고, 절대 들어올 수 없는 조합은 don't care로 명시해 최적화에 활용한다. (확인: 진리표 커버리지 100%)

## 5. 실무 적용 사례

| 적용 영역 | 어떻게 쓰나 | 무엇으로 효과를 확인하나 |
|:---|:---|:---|
| CPU 산술연산장치(ALU) | 전가산기를 이어 붙여 덧셈·뺄셈을 처리하고 캐리 예측으로 속도를 확보 | 연산 지연, 최대 클럭 |
| 데이터 경로의 선택 | 멀티플렉서로 여러 버스 입력 중 하나를 골라 다음 단으로 전달 | 선택 정확도, fan-out 여유 |
| 메모리·장치 주소 디코딩 | 디코더로 주소를 받아 해당 칩·장치의 선택 신호 하나만 켬 | 신호 충돌 여부, 디코딩 지연 |

> 요약: 계산은 가산기, 여럿 중 하나 고르기는 MUX, 주소로 대상 지정하기는 디코더가 맡는다.

## 6. 결론

조합 논리 회로는 기억이 필요 없는 계산을 게이트만으로 엮어 입력 즉시 출력을 뽑는, 디지털 설계의 바탕 구조다. 그래서 회로가 맞는지는 진리표 하나로 완전히 검증되지만, 실무의 진짜 관건은 기능이 아니라 게이트를 겹겹이 지나며 쌓이는 전파 지연을 어떻게 줄이고(캐리 예측·논리 단순화) 입력 전환 순간의 글리치를 어떻게 잠재우느냐(여유항·클럭 동기화)에 있다. 조합 논리와 순서 논리의 경계를 먼저 잡아야, 가산기·MUX 같은 대표 회로를 어디에 쓰고 무엇을 개선할지가 자연스럽게 이어진다.
