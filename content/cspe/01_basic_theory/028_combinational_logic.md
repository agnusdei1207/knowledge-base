## Ⅰ. 개요
- **정의**: 출력이 현재 입력의 조합만으로 결정되며, 내부 상태(기억)를 갖지 않는 논리 회로
- **배경/필요성**: 산술 연산, 데이터 선택, 주소 해석 등 디지털 시스템의 데이터 경로를 구성하려면 입력-출력 간 즉시 매핑되는 회로 블록이 필요함
- **비유**: 자판기와 같음 — 투입한 동전(입력)만으로 상품(출력)이 즉시 결정되고, 이전 투입 이력은 결과에 영향을 주지 않음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 조합 회로 설계 절차 이해 | 진리표 → 논리식 → 카르노 맵 간소화(027 참조) → 게이트 구현 | 순서 논리(029 참조)와의 차이(기억 소자 유무) 명확히 구분 |
| 주요 조합 회로 블록 활용 | 반가산기/전가산기, 멀티플렉서, 디코더 구조와 용도 | 전가산기의 캐리 입력(`Cin`) 누락 주의 |

> 요약: 조합 논리 회로는 기억 소자 없이 현재 입력만으로 출력을 생성하는 데이터 경로의 기본 블록임

## Ⅱ. 구성요소
```text
             조합 논리 회로
                  |
    +------+------+------+------+
    |      |      |      |      |
  가산기  감산기 디코더   MUX  인코더
    |
  +---+---+
  |       |
 HA      FA
(반가산) (전가산)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 반가산기(HA) | 1비트 두 입력의 합(`S`)과 캐리(`C`)를 출력 — `S = A ^ B`, `C = A * B` | 한 자리 덧셈: 받아올림 입력 없이 두 수만 더함 |
| 전가산기(FA) | 반가산기에 하위 캐리 입력(`Cin`)을 추가하여 3입력 1비트 덧셈 수행 | 여러 자리 덧셈: 아래 자리 받아올림까지 반영함 |
| 디코더 | n비트 입력을 2^n개 출력 중 하나만 활성화 — 주소 해석에 사용 | 우편함 번호판: 번호 입력 시 해당 칸만 열림 |
| 멀티플렉서(MUX) | 선택 신호에 따라 2^n개 입력 중 하나를 출력으로 전달 | 철도 전환기: 선택 레버로 한 선로만 연결함 |
| 인코더 | 2^n개 입력 중 활성화된 하나의 위치를 n비트 이진 코드로 출력 | 디코더의 역변환: 활성 칸 번호를 이진으로 읽음 |

> 요약: 가산기·디코더·멀티플렉서·인코더가 조합 논리 회로의 핵심 빌딩 블록임

## Ⅲ. 절차
```text
요구사항 정의 --> 진리표 작성 --> 논리식 도출(SOP/POS)
                                        |
                                        v
                              카르노 맵 간소화(027 참조)
                                        |
                                        v
                              게이트 회로 구현 / 검증
```
- 1단계: **진리표 작성** — 모든 입력 조합에 대해 각 출력 비트의 값을 0/1로 정의함
- 2단계: **논리식 도출** — 출력이 1인 행을 최소항으로 묶어 SOP 형태 또는 최대항으로 묶어 POS 형태의 부울식을 작성함
- 3단계: **논리식 간소화** — 카르노 맵 또는 퀸-맥클러스키 알고리즘으로 중복 항을 제거하여 게이트 수를 최소화함(027 참조)
- 4단계: **게이트 구현·검증** — 간소화된 식을 게이트 레벨로 변환하고, 시뮬레이션으로 진리표와 일치하는지 검증함

> 요약: 진리표 → 논리식 → 간소화 → 게이트 구현의 4단계로 조합 회로를 설계함

## Ⅳ. 문제점
- **캐리 전파 지연**: 리플 캐리 가산기에서 하위 비트의 캐리가 최상위 비트까지 순차 전파됨 — n비트 가산 시 지연이 O(n)으로 증가하여 고속 연산에 병목이 됨
- **팬아웃 과부하**: 하나의 게이트 출력이 다수의 후속 게이트 입력에 연결되면 구동 능력 초과로 신호 품질이 저하됨 — 오동작 유발 가능
- **Don't-care 미활용**: 설계 시 무관 조건을 식별하지 않으면 불필요한 게이트가 잔존함 — 칩 면적과 전력이 낭비됨

> 요약: 캐리 전파 지연, 팬아웃 과부하, 무관 조건 미활용이 조합 회로의 주요 문제임

## Ⅴ. 개선방안
1. 단기: 캐리 룩어헤드 가산기(CLA)를 적용하여 캐리 전파를 O(log n)으로 단축함
2. 중기: 버퍼 게이트를 삽입하거나 팬아웃 트리를 구성하여 구동 능력을 분산함
3. 장기: EDA 합성 도구에서 Don't-care 조건을 자동 탐지·활용하여 게이트 수를 최적화함

> 요약: CLA 도입, 팬아웃 분산, Don't-care 자동 활용으로 각 문제를 해결함

## Ⅵ. 전망
- 발전 방향: FPGA/ASIC 설계에서 조합 블록이 IP 코어로 표준화되어 재사용성이 높아지고 있으며, HDL 기반 자동 합성이 보편화됨
- 기술사적 판단: 조합 논리는 순서 논리(029 참조)의 데이터 경로를 구성하고, 해밍 코드(030 참조) 등 오류 검출 회로의 기반이므로 기초 설계 역량의 핵심임
- 기술사 제언: 전가산기 구조와 캐리 룩어헤드 원리를 답안에 함께 서술하고, 진리표에서 회로까지 설계 절차를 단계별로 전개하는 것을 권장함
