# 📖 【암기용】 개념 완전 이해

> 목적: 유사도 측정을 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 두 데이터가 얼마나 가까운지 또는 같은 속성을 공유하는지 수치화하는 기준
- **왜 필요한가**: 검색, 추천, 중복 탐지, 클러스터링은 "비슷함"을 계산해야 다음 후보를 고를 수 있음
- **핵심 직관**: 데이터의 양을 볼지, 방향을 볼지, 공통 원소를 볼지에 따라 거리·유사도 공식이 달라짐

## 깊이 이해
- **배경·문제의식**: 문서, 사용자, 이미지 임베딩, 집합 데이터는 형태가 다름
- 같은 "유사"라도 문서 검색은 방향, 위치 데이터는 거리, 태그 비교는 교집합 비율이 맞음
- **작동 원리**: 코사인 유사도는 벡터 각도를, 유클리드 거리는 좌표 간 직선 거리를, 자카드 유사도는 교집합/합집합 비율을 계산함.
- **비유**: 두 사람이 같은 방향을 보고 있으면 코사인 유사도, 서로 실제로 얼마나 떨어졌는지는 유클리드 거리, 가진 물건 목록의 겹침은 자카드 유사도임.
- **구체 예시**: 문서 임베딩 검색에서 코사인 0.82 이상을 후보로 뽑고, 사용자 태그 `{AI,DB,Cloud}`와 `{AI,Cloud,Security}`의 자카드는 2/4=0.5임.
- **흔한 오해·주의점**: 코사인은 벡터 크기를 무시하므로 구매금액 규모 차이를 놓칠 수 있음
- 유클리드는 스케일에 민감해 표준화가 필요함

## 연결 개념
- 클러스터링: 거리 척도가 군집 모양을 결정
- 벡터 검색: 임베딩 유사도 기반 Top-k 검색
- 추천 시스템: 사용자·아이템 유사도 계산에 활용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 유사도 측정은 벡터·집합·좌표 데이터 간 가까움과 겹침을 정량화하는 기준임.
> 2. **가치**: 검색 Top-k, 추천 후보, 군집 할당, 중복 제거에서 후보 선택 기준을 수치로 고정함.
> 3. **판단 포인트**: 데이터 표현, 스케일, 희소성, 차원 수, 임계값이 지표 선택과 결과 품질을 좌우함.

---

## Ⅰ. 개요 및 필요성

- 개요: 유사도 측정은 데이터 간 가까움을 계산하는 기준임
- 배경: AI 검색과 추천 시스템은 후보를 전부 비교하지 않고 유사도 점수로 정렬함
- 필요성: 지표 선택이 잘못되면 Top-k 결과와 군집 경계가 왜곡되므로 데이터 유형에 맞는 지표 선정이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
데이터 표현 -> 전처리/정규화 -> 유사도·거리 계산 -> 임계값/Top-k 선택
              / 벡터·집합·좌표 데이터 유형 선택
```

| 구성요소 | 역할 | 판단 기준 |
|:---|:---|:---|
| 벡터 표현 | 문서·이미지·사용자를 수치화 | 임베딩 차원, 희소성 |
| 정규화 | 스케일 차이와 크기 영향 조정 | L2 정규화, 표준화 |
| 거리·유사도 함수 | 가까움 계산 | 코사인, 유클리드, 자카드 |
| 선택 기준 | 후보 채택·정렬 | Top-k, threshold |

> 요약: 유사도 측정은 데이터 표현과 정규화를 먼저 정한 뒤 목적에 맞는 함수를 선택해 후보를 산출함.

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 데이터 -> 벡터/집합 변환 -> 정규화 -> 점수 계산 -> Top-k/임계값 판정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서·사용자·태그를 벡터 또는 집합으로 변환 | 차원, 희소도 |
| 2 | 표준화 또는 L2 정규화 수행 | 평균 0, 단위 길이 |
| 3 | 코사인·유클리드·자카드 점수 계산 | 값 범위, 거리 방향 |
| 4 | Top-k 또는 threshold로 후보 선택 | Recall@k, Precision@k |

> 요약: 유사도는 표현 변환과 정규화 이후 계산하며, 검색·추천에서는 Top-k 지표로 임계값을 조정함.

---

## Ⅳ. 특징

| 구분 | 코사인 | 자카드 | 유클리드 |
|:---|:---|:---|:---|
| 기준 | 벡터 각도 | 교집합/합집합 | 좌표 직선 거리 |
| 적합 데이터 | 문서·임베딩 | 태그·집합 | 수치 좌표 |
| 값 범위 | -1~1 또는 0~1 | 0~1 | 0 이상 |
| 주의점 | 크기 정보 손실 | 빈도 정보 손실 | 스케일 민감 |

> 요약: 문서·임베딩은 코사인, 집합형 태그는 자카드, 동일 스케일 수치 좌표는 유클리드 기준을 우선 검토함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존·대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 키워드 일치 검색은 문자열 포함 여부 판단 | 유사도는 벡터·집합·좌표 점수로 후보 정렬 | 의미 검색·추천·군집화 필요 시 선택 |
| 비용/성능 | 전수 비교는 O(n^2) 비용 발생 | ANN 인덱스(HNSW, IVF-PQ)로 Top-k 탐색 | Recall@10, p95 검색지연 기준 |
| 운영/위험 | 단일 임계값은 데이터 분포 변화 취약 | threshold·Top-k·정규화 정책을 실험으로 조정 | Precision@k, Recall@k, 임계값 곡선 |

> 요약: 유사도 측정은 데이터 표현에 맞는 지표와 검색 인덱스를 함께 선택해야 후보 품질과 탐색 비용을 통제함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 스케일 왜곡 | 유클리드 거리의 단위 민감성 | 표준화, L2 정규화 적용 | 변수 분산, 거리 분포 |
| 의미 손실 | 자카드의 빈도 무시, 코사인의 크기 무시 | TF-IDF, 가중 자카드, 크기 피처 병행 | Precision@k, NDCG |
| 검색 지연 | 대규모 전수 비교 | HNSW efSearch 조정, IVF-PQ 압축 | p95 지연, Recall@k |

> 요약: 유사도 리스크는 스케일·정보 손실·검색 비용이므로 정규화, 가중치, ANN 지표를 함께 관리함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검색 품질 | Recall@10 0.9 이상, NDCG@10 측정 | 라벨셋 평가, A/B 테스트 |
| 계산 비용 | p95 검색지연 100ms 이하 | 벡터DB 로그, 부하 테스트 |
| 임계값 운영 | 오탐·누락률 월별 추적 | threshold sweep, 혼동행렬 |

> 요약: 도입 후에는 검색 품질, 지연시간, 임계값별 오탐·누락률을 지속 측정해야 함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 벡터 검색: 768차원 임베딩을 L2 정규화하고 코사인 Top-10 후보를 검색해 Recall@10으로 튜닝
2. 중복 탐지: URL·태그 집합에 자카드 0.8 이상 기준을 적용하고 MinHash로 대량 비교 비용 절감
3. 군집 분석: 수치형 운영 지표는 표준화 후 유클리드 거리로 K-Means 수행, Silhouette 0.5 이상 목표 설정

**결론 (2줄):**
- 기술사 판단: 데이터가 방향 중심이면 코사인, 공통 원소 중심이면 자카드, 좌표 거리 중심이면 유클리드를 선택함
- 향후 방향: 대규모 검색은 HNSW, IVF-PQ 같은 ANN 인덱스와 Recall@k 평가를 함께 설계해야 함
