## 미리 알고가기

- **특징 벡터 (Feature Vector)**: 데이터의 특성을 수치화하여 n차원 공간에 나타낸 벡터
- **희소 행렬 (Sparse Matrix)**: 데이터 요소 중 대부분이 0인 행렬 (예: 문서 내 단어 출현 빈도). 유사도 선택 시 핵심 고려사항임
- **거리 척도 (Distance Metric)**: 값이 작을수록 유사함을 의미하는 지표 (유클리드 등). 유사도는 반대로 클수록 비슷함을 의미함

## 1. 개요

- **정의/개념**: 유사도 측정(Similarity Measures)은 두 데이터 객체가 서로 얼마나 닮았는지를 정량적인 수치(0~1 등)로 산출하는 방법론임. 데이터의 형태(수치, 집합, 텍스트)에 따라 최적의 계산 방식이 달라짐
- **배경/필요성**: 검색 엔진에서 관련 문서를 찾거나, 쇼핑몰에서 나와 취향이 비슷한 사용자를 추천(협업 필터링)하고, 수만 장의 사진을 군집화하기 위해서는 "비슷하다"라는 모호한 개념을 컴퓨터가 이해할 수 있는 숫자로 정의해야 함. 잘못된 유사도 지표 선택은 모델의 성능 저하뿐 아니라 도메인 맥락에 어긋난 엉뚱한 추천 결과를 초래함

## 2. 특징 및 비교

### 가. 3대 주요 유사도 측정 방식 비교

| 구분 | 유클리드 거리 (Euclidean) | 코사인 유사도 (Cosine) | 자카드 유사도 (Jaccard) |
|:---|:---|:---|:---|
| 핵심 기준 | 두 점 사이의 직선 물리 거리 | 두 벡터 사이의 사잇각($\theta$) | 두 집합 간의 공유 원소 비율 |
| 연산 식 | $\sqrt{\sum(x_i - y_i)^2}$ | $\frac{A \cdot B}{\|A\|\|B\|}$ | $\frac{\|A \cap B\|}{\|A \cup B\|}$ |
| 값의 범위 | 0 ~ $\infty$ (작을수록 유사) | -1 ~ 1 (1에 가까울수록 유사) | 0 ~ 1 (1에 가까울수록 유사) |
| 적합 데이터 | 일반적 수치, 센서 값 | 문서 데이터, 고차원 희소 벡터 | 해시태그, 구매 목록, 집합 |
| 특징 | 데이터의 절대적 크기가 중요 | 데이터의 크기보다 방향이 중요 | 빈도는 무시하고 존재 여부만 봄 |

> 요약: 값의 차이가 중요하면 유클리드, 방향(패턴)이 중요하면 코사인, 공유 멤버가 중요하면 자카드를 씀

### 나. 상황별 유사도 선택 가이드
- **스케일 차이가 클 때**: 유클리드보다는 방향성만 보는 코사인이 유리함
- **데이터가 매우 희소할 때**: 0이 아닌 요소의 겹침만 보는 자카드가 효율적임
- **단어의 출현 빈도가 중요할 때**: 자카드보다는 코사인이나 피어슨 상관계수가 적합함

## 3. 구성요소/구조

### 가. 유사도 분석 시스템의 데이터 처리 흐름

```text
[원시 데이터] -> [특징 추출/임베딩] -> [정규화/표준화] -> [유사도 연산] -> [결과 정렬/추천]

1. 특징 추출: 텍스트는 TF-IDF 또는 Word2Vec으로, 이미지는 CNN 특징 맵으로 변환
2. 정규화: 거리 기반 지표 사용 시 단위 차이에 의한 왜곡 방지
3. 연산: 도메인에 적합한 메트릭(Metric) 적용
4. 활용: 임계값(Threshold)을 넘는 항목을 추출하거나 상위 K개 선정
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 특징 공간 (Feature Space) | 데이터가 수치화되어 배치되는 n차원 공간 | 차원이 높을수록 유사도 변별력 저하 주의 |
| 가중치 (Weighting) | 특정 변수의 중요도를 높여 유사도 계산 | TF-IDF와 같이 정보량이 많은 변수 우대 |
| 임계값 (Threshold) | 유사함과 유사하지 않음을 가르는 기준 | 비즈니스 목적에 따른 정밀도/재현율 튜닝 |
| 커널 함수 (Kernel) | 데이터를 고차원으로 사상하여 유사도를 재정의 | 비선형적 관계를 파악할 때 활용 |

> 요약: 데이터의 수치적 특성을 반영하는 '좌표계'와 이를 비교하는 '자(Scale)'를 설정하는 과정임

## 4. 문제점 및 개선방안

1. **차원의 저주로 인한 변별력 상실**: 차원이 수천 개 이상으로 늘어나면 모든 데이터 간의 거리가 멀어지고 차이가 미미해짐
   - **개선방안**: PCA나 오토인코더를 통해 차원을 축소한 후 유사도를 계산하거나, 로컬 민감 해싱(LSH)을 통해 유사한 후보군을 먼저 압축함

2. **데이터 스케일 및 단위 편향**: 단위가 큰 특정 변수가 전체 유사도(특히 유클리드)를 지배함
   - **개선방안**: Z-Score 표준화나 L2 정규화를 통해 모든 변수의 벡터 길이를 맞추거나 가중치를 조정함

3. **의미적 유사성(Semantic) 파악 불가**: 단순 키워드 매칭 기반 유사도는 '차'와 '자동차'를 서로 다른 것으로 인식함
   - **개선방안**: 딥러닝 임베딩(Word2Vec, BERT)을 활용하여 의미적 공간에서의 벡터 유사도를 측정함

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 전자상거래 추천 | 사용자별 구매 상품 집합에 자카드 유사도를 적용해 '이 상품을 산 다른 고객' 추천 | CTR(클릭률), 구매 전환율 |
| 뉴스 유사도 검색 | 뉴스 본문의 단어 빈도 벡터(TF-IDF)에 코사인 유사도를 적용해 관련 기사 묶음 | 정밀도(Precision), 군집 일관성 |
| 보안 로그 분석 | 평상시 접속 IP, 시간대의 유클리드 거리를 측정해 임계치를 벗어난 이상 징후 탐지 | 오탐률(FPR), 미탐률(FNR) |

> 요약: 추천은 자카드/코사인, 정밀 수치 비교는 유클리드, 문맥 이해는 임베딩 기반 코사인을 주로 활용함

## 6. 결론

유사도 측정은 "무엇이 비슷한가"라는 주관적 판단을 수학적 질서로 치환하는 지능형 시스템의 입구임. 단순한 수식 적용을 넘어, 데이터의 희소성, 변수의 척도, 비즈니스의 최종 목적을 아우르는 메트릭 선택이 모델의 성패를 가름함.

기술사는 서비스 기획 단계부터 데이터의 특성을 파악하여, 연산 비용과 정확도 사이의 균형을 맞춘 유사도 지표를 제안할 수 있어야 함. 특히 AI 임베딩 기술이 발전함에 따라, 단순 통계 기반 유사도에서 의미론적 유사도로 진화하는 기술 트렌드를 반영하여 더 정교한 시스템을 설계할 수 있는 통찰력이 요구됨.
