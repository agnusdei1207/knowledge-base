# 유사도 측정 - 코사인·자카드·유클리드 (Similarity Measures)

## 1. 개요

- **정의/개념**: 유사도 측정은 두 데이터 객체가 얼마나 가까운지 또는 비슷한지를 수치로 표현하는 기준이다.
- **배경/필요성**: 검색, 추천, 군집화, 중복 탐지에서는 모델보다 먼저 "무엇을 비슷하다고 볼 것인지"를 정의해야 결과 해석이 가능하다.

유사도는 데이터 표현 방식에 따라 달라지므로, 벡터·집합·공간 좌표 중 어떤 구조인지 먼저 판단해야 한다.

## 2. 특징 및 비교

| 구분 | 코사인 유사도 | 자카드 유사도 | 유클리드 거리 |
|---|---|---|---|
| 기준 | 벡터 방향 | 집합의 교집합/합집합 | 좌표 간 직선 거리 |
| 값 해석 | 방향이 비슷할수록 큼 | 공유 원소 비율 | 작을수록 가까움 |
| 적합 데이터 | 문서 임베딩, 희소 벡터 | 태그, 구매 집합 | 연속형 수치 |
| 주의점 | 크기 정보 무시 | 빈도 정보 약함 | 스케일 민감 |

선택 기준은 데이터 타입, 스케일, 희소성, 크기 정보 필요 여부, 해석 목적이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Representation | 벡터, 집합, 좌표 표현 | 유사도 선택 출발점 |
| Metric Function | 유사도·거리 계산식 | 해석 기준 |
| Normalization | 크기·스케일 보정 | 왜곡 방지 |
| Threshold | 유사 여부 판단 기준 | 오탐·미탐 조정 |
| Evaluation | 검색·추천 품질 검증 | precision, recall |

```text
+----------+      +----------+      +----------+      +----------+
| 데이터표현 | ---> | 정규화   | ---> | 유사도계산 | ---> | 임계값판단 |
+----------+      +----------+      +----------+      +----------+
```

표현과 정규화가 먼저 맞아야 유사도 값이 실제 도메인 의미와 연결된다.

## 4. 문제점 및 개선방안

1. **스케일 영향**
   - 유클리드 거리는 변수 단위가 큰 feature에 지배될 수 있다.
   - **개선방안**: 표준화, min-max scaling, feature weighting을 적용한다.

2. **희소 데이터 해석 오류**
   - 문서·태그 데이터에서 단순 거리만 쓰면 0이 많은 구조를 제대로 반영하지 못한다.
   - **개선방안**: 코사인, 자카드, TF-IDF 기반 표현을 사용한다.

3. **임계값 임의 설정**
   - 유사도 threshold가 업무 비용과 맞지 않으면 오탐·미탐이 커진다.
   - **개선방안**: ROC/PR curve, 도메인 비용 기준으로 임계값을 조정한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 문서 검색 | TF-IDF·임베딩 벡터에 코사인 유사도 적용 | precision@k |
| 추천 시스템 | 사용자 구매 집합에 자카드 유사도 적용 | CTR, hit rate |
| 이상 탐지 | 정상 패턴과의 거리로 이상 점수 계산 | 오탐률, 탐지율 |

## 6. 결론

유사도 측정은 데이터 간 관계를 수치화하는 검색·추천·군집화의 출발점이다. 코사인·자카드·유클리드는 데이터 표현과 해석 목적이 다르므로, 스케일·희소성·임계값을 함께 판단해야 한다.
