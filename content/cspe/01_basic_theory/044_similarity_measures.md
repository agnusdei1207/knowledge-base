## 미리 알고가기

- **특징 벡터 ($Feature$ $Vector$)**: 데이터를 $n$차원 공간의 좌표로 변환한 수치적 표현
- **희소 행렬 ($Sparse$ $Matrix$)**: 대부분의 원소가 $0$인 행렬 (예: 문서 내 단어 빈도 데이터)
- **L2 정규화 ($L2$ $Normalization$)**: 벡터의 길이를 $1$로 맞추어 크기 편향을 제거하는 전처리 기법

## Ⅰ. 개요

- **정의/개념**: 데이터 객체 간의 닮음 정도를 정량적인 수치($0 \sim 1$ 또는 거리값)로 산출하는 방법론임. 데이터의 도메인(수치, 집합, 텍스트)과 구조적 특성에 따라 최적의 수리적 메트릭($Metric$)을 적용함
- **배경/필요성**: 정성적인 '유사함'을 컴퓨터가 처리 가능한 '수치'로 객관화하여 자동화된 판단 체계를 구축하기 위함임. 추천 엔진의 개인화 알고리즘, 검색 엔진의 랭킹 모델, 보안 관제의 이상 탐지 등에서 의사결정의 핵심 판단 척도로 활용됨

## Ⅱ. 특징 및 비교

### 가. 3대 주요 유사도 및 거리 척도 기술 비교

| 구분 | 유클리드 거리 ($Euclidean$) | 코사인 유사도 ($Cosine$) | 자카드 유사도 ($Jaccard$) |
|:---|:---|:---|:---|
| 핵심 메커니즘 | 두 점 사이의 최단 직선 물리 거리 | 두 벡터 사이의 사잇각($\theta$) | 두 집합 간의 공유 원소 비율 |
| 수학적 정의 | $d = \sqrt{\sum (x_i - y_i)^2}$ | $Sim = \frac{A \cdot B}{\|A\|\|B\|}$ | $Sim = \frac{|A \cap B|}{|A \cup B|}$ |
| 값의 범위 | $[0, \infty)$ (작을수록 유사) | $[-1, 1]$ ($1$에 가까울수록 유사) | $[0, 1]$ ($1$에 가까울수록 유사) |
| 데이터 특성 | 연속형 수치 데이터 (좌표) | 고차원 희소 데이터 (텍스트) | 이진/범주형 데이터 (집합) |
| 주요 강점 | 절대적 거리 차이 정밀 반영 | 데이터 크기(길이) 불변성 확보 | 공통 원소의 존재 여부에 집중 |

> 요약: 값의 절대적 편차가 중요하면 유클리드, 패턴의 방향성이 핵심이면 코사인, 집합적 겹침을 중시하면 자카드를 선정함

### 나. 기술적 트레이드오프 및 선택 가이드 (PPA 관점)
- **차원성 ($Dimensionality$)**: 차원이 높아질수록 모든 점 간의 거리가 멀어지는 '차원의 저주' 발생. 고차원에서는 코사인 유사도가 상대적으로 견고함
- **희소성 ($Sparsity$)**: 텍스트 임베딩과 같이 $0$이 많은 데이터에서는 내적($Dot$ $Product$) 기반의 코사인 유사도가 연산 효율과 의미 보존 측면에서 유리함
- **스케일 ($Scale$)**: 문서 길이나 음량 차이 등 크기에 무관하게 패턴만 추출하려면 코사인 유사도가 필수적임

## Ⅲ. 구성요소/구조

### 가. 유사도 분석 아키텍처 인사이트 ($Architecture Insight$)

```text
   [Raw Data]        [Feature Extraction]      [Similarity Engine]       [Decision Layer]
  +----------------+    +----------------+    +------------------+    +------------------+
  | Logs / Text /  | -> | Embedding /    | -> | Metric Processor | -> |  Rank / Cluster  |
  | Sensor Data    |    | Normalization  |    | (Math Op, SIMD)  |    |  (Thresholding)  |
  +----------------+    +----------------+    +------------------+    +------------------+
          |                      |                       |                       |
    Pre-processing         L2 Normalization        Distance Indexing       Business Action
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 (Performance/Trade-off) |
|:---|:---|:---|
| 특징 공간 ($Feature$ $Space$) | 데이터가 수치화되어 사상되는 좌표계 | 차원 축소($PCA$)를 통한 연산 가속 필수 |
| 임베딩 ($Embedding$) | 원시 데이터를 수치 벡터로 변환 | 의미론적 유사성($Semantic$ $Sim$) 확보 |
| 가중치 ($Weighting$) | 차원별 중요도를 조정하는 인자 | $TF-IDF$, $Attention$ 메커니즘 연동 |
| 거리 인덱스 ($Indexing$) | 대규모 벡터 간 고속 검색 지원 | $HNSW$, $IVF$ 등 근사 검색($ANN$) 기법 |
| 임계값 ($Threshold$) | 유사 여부를 가르는 비즈니스 경계 | 정밀도($Precision$)와 재현율($Recall$)의 상충 |

> 요약: 특징 추출, 벡터 정규화, 고속 인덱싱을 통해 데이터 간 수리적 거리를 확정하는 구조임

## Ⅳ. 절차/동작 원리

1. **데이터 벡터화**: 원시 데이터를 수치형 특징 벡터($v$)로 변환하고 필요시 $L2$ $Normalization$ 수행
2. **메트릭 선정**: 분석 목적(집합 비교, 방향성 비교, 수치 거리)에 부합하는 유사도 공식 선택
3. **유사도 연산**: 특징 벡터 간의 거리 또는 각도를 계산하여 점수($Score$) 산출
4. **결과 활용**: 점수 기반의 랭킹 생성, 특정 임계값($Threshold$)에 의한 필터링 또는 군집화 수행

## Ⅴ. 문제점 및 개선방안

1. **차원의 저주 ($Curse$ $of$ $Dim.$)**: 차원이 극도로 높을 경우 모든 객체 간 유사도가 수렴하여 변별력이 상실됨
   - **개선방안**: $Autoencoder/PCA$를 이용한 차원 압축, $LSH$(로컬 민감 해싱)를 활용한 근사 유사도 탐색
2. **의미적 단절 ($Semantic$ $Gap$)**: 단순 키워드 빈도나 물리 거리 기반 측정은 문맥적 동의어를 처리하지 못함
   - **개선방안**: $BERT$, $GPT$ 등 사전 학습 모델 임베딩 공간에서 코사인 유사도를 측정하여 문맥 반영
3. **연산 복잡도 ($O(N^2)$)**: 데이터가 $100$만 건 이상일 경우 모든 쌍의 유사도 계산은 물리적으로 불가능함
   - **개선방안**: 벡터 데이터베이스(Vector DB) 도입 및 $FAISS$와 같은 고속 ANN 알고리즘 적용

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 (Validation) |
|:---|:---|:---|
| 개인화 추천 | 사용자 구매 이력 기반 자카드 유사도 산출 및 협업 필터링 | 클릭률($CTR$), 구매 전환율 |
| 중복 문서 탐지 | 뉴스 기사 본문의 $TF-IDF$ 벡터 간 코사인 유사도 분석 | 군집 일관성, 중복 제거율 |
| 보안 이상 탐지 | 접속 로그의 $Z-Score$ 정규화 후 유클리드 기반 이상점 식별 | 오탐률($FPR$), 탐지 지연 시간($Latency$) |

> 요약: 도메인 특성에 부합하는 메트릭 선택과 고속 검색 인덱싱을 통해 시스템의 실시간성과 정확성을 확보함

## Ⅶ. 결론

유사도 측정은 정성적인 '닮음'을 수치적 실체로 구체화하는 데이터 지능의 기초 인프라임. 단순 수식 적용보다는 데이터의 **희소성, 스케일, 의미론적 깊이**를 종합적으로 고려한 '맥락적 메트릭 선택'이 아키텍처의 성패를 좌우함.

기술사는 대규모 시스템 설계 시 $O(N^2)$의 연산 부하를 해결하기 위해 벡터 인덱싱($HNSW$ 등) 기술을 적극 도입해야 하며, 의미적 유사성을 극대화하기 위해 최신 딥러닝 임베딩 기술과 전통적 유사도 메트릭을 결합한 하이브리드 아키텍처를 제시할 수 있어야 함.
