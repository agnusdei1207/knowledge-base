# 정렬 알고리즘 비교 - 퀵·병합·힙·버블 (Sorting Algorithms)

## 1. 개요

- **정의/개념**: 정렬 알고리즘은 데이터를 키 기준 순서로 재배열하여 탐색, 병합, 집계, 중복 제거 같은 후속 처리를 가능하게 하는 알고리즘이다.
- **배경/필요성**: 정렬 비용은 데이터 파이프라인 전체 성능에 영향을 주므로, 평균 속도뿐 아니라 최악 시간, 안정성, 메모리 사용, 외부 저장장치 조건을 함께 고려해야 한다.

## 2. 특징 및 비교

| 알고리즘 | 평균 시간 | 최악 시간 | 공간 | 안정성 | 선택 기준 |
|---|---:|---:|---:|---|---|
| **퀵 정렬** | `O(n log n)` | `O(n²)` | 재귀 스택 | 기본 불안정 | 평균 성능, 캐시 효율 |
| **병합 정렬** | `O(n log n)` | `O(n log n)` | `O(n)` | 안정 가능 | 안정성, 외부 정렬 |
| **힙 정렬** | `O(n log n)` | `O(n log n)` | `O(1)` | 불안정 | 메모리 제한, 최악 보장 |
| **버블 정렬** | `O(n²)` | `O(n²)` | `O(1)` | 안정 가능 | 교육용, 소규모 검증 |

- 퀵 정렬은 평균 성능이 좋지만 피벗 편향 시 최악이 나빠진다.
- 병합 정렬은 안정성과 예측 가능한 시간이 강점이나 추가 버퍼가 필요하다.
- 힙 정렬은 제자리 정렬과 최악 시간 보장이 강점이나 캐시 효율은 상대적으로 낮을 수 있다.
- 정렬 선택은 평균 시간뿐 아니라 최악 시간, 안정성, 보조 공간, 입력 분포, 외부 저장장치 조건을 함께 본다.

## 3. 구성요소 및 동작 원리

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| 정렬 키 | 순서를 결정하는 기준 값 | 다중 키, 동등 키 정책 |
| 비교 함수 | 두 원소의 선후 관계를 판단 | 반사성·반대칭성·추이성 |
| 재배치 전략 | 분할, 병합, 힙 구성, 인접 교환 | 알고리즘별 비용 차이 |
| 보조 공간 | 병합 버퍼, 재귀 스택 등 | 메모리 제약 판단 |

```text
요구 조건 확인 -> 정렬 방식 선택 -> 비교/이동 수행 -> 정렬성·안정성 검증
```

## 4. 문제점 및 개선방안

1. **퀵 정렬 최악 입력**
   - 피벗이 편향되면 `O(n²)`로 악화된다.
   - **개선방안**: 무작위 피벗, median-of-three, 인트로소트(Introsort)를 적용한다.

2. **안정성 요구 누락**
   - 다중 키 정렬에서 같은 키의 상대 순서가 깨지면 결과 의미가 달라진다.
   - **개선방안**: 안정 정렬을 선택하거나 동등 키 정책을 명확히 한다.

3. **외부 정렬 미고려**
   - 데이터가 메모리를 초과하면 내부 정렬 복잡도만으로 판단할 수 없다.
   - **개선방안**: 외부 병합 정렬, 파티션 정렬, I/O 비용을 함께 설계한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 로그·이벤트 처리 | 시간순 안정 정렬 또는 외부 정렬 적용 | 처리량, 임시 파일 크기 |
| 사용자 목록 정렬 | 다중 키 비교 함수와 안정성 정책 적용 | 정렬 정확도, 응답 지연 |
| 대용량 배치 | 분산 정렬·외부 병합 정렬 적용 | shuffle 비용, I/O 횟수 |

## 6. 결론

정렬 알고리즘 선택은 평균 시간복잡도만으로 결정하지 않는다. 퀵·병합·힙·버블은 시간, 공간, 안정성, 입력 분포, 외부 정렬 가능성 중 요구사항에 직결되는 차원을 중심으로 비교해야 선택 근거가 명확해진다.
