## Ⅰ. 개요
- **정의**: 데이터 집합의 원소를 특정 키 기준으로 오름차순 또는 내림차순 배치하는 알고리즘 군
- **배경/필요성**: 탐색·병합·중복 제거 등 후속 연산의 전제 조건이 정렬이므로, 자원 효율적인 정렬 기법이 필요함
- **비유**: 도서관에서 책을 제목순으로 꽂아 두면 원하는 책을 빠르게 찾을 수 있는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정렬 기법별 복잡도·특성 비교 | 비교 기반 하한 O(n log n), 안정성, in-place 구분 | Merge와 Quick의 최악 복잡도 차이를 정확히 구분 |

> 요약: 데이터를 순서대로 배치하여 후속 연산의 효율을 확보하는 기초 알고리즘 군임

## Ⅱ. 구성요소
```text
                    +--- Bubble Sort --- O(n^2), 안정, in-place
                    |
                    +--- Insertion Sort --- O(n^2), 안정, in-place
  정렬 알고리즘 ----+
                    +--- Merge Sort --- O(n log n), 안정, 추가 메모리 O(n)
                    |
                    +--- Quick Sort --- 평균 O(n log n), 불안정, in-place
                    |
                    +--- Heap Sort --- O(n log n), 불안정, in-place
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Bubble Sort | 인접 원소를 반복 비교·교환하여 최대값을 끝으로 이동, `O(n^2)` | 거품이 수면 위로 떠오르는 과정 |
| Insertion Sort | 정렬된 부분 배열에 새 원소를 적절한 위치에 삽입, `O(n^2)` | 카드패를 한 장씩 받아 제자리에 꽂는 것 |
| Merge Sort | 배열을 반씩 분할 후 정렬된 부분을 병합, `O(n log n)` 보장 | 두 묶음의 정렬된 서류를 하나로 합치는 것 |
| Quick Sort | 피벗 기준 분할 후 재귀 정렬, 평균 `O(n log n)`, 최악 `O(n^2)` | 기준값보다 큰/작은 그룹으로 나누는 분류 작업 |
| Heap Sort | 최대 힙을 구성하여 루트를 반복 추출, `O(n log n)` 보장 | 우선순위 줄 세우기에서 1등부터 차례로 빼는 것 |

> 요약: 정렬 알고리즘은 복잡도·안정성·추가 메모리 사용 여부로 구분되며 용도에 따라 선택함

## Ⅲ. 절차
```text
  입력 수신          분할/비교          정렬 수행          결과 병합/출력
  (배열 입력)       (기준 선택)       (교환/삽입/병합)   (정렬 배열 반환)
   |                 |                 |                 |
   +----입력-------->+----분할-------->+----정렬-------->+
  n개 원소          피벗/중간점       재귀/반복 처리     최종 정렬 배열
```
- 1단계: 정렬 대상 배열을 입력받고 크기 `n`을 확인함
- 2단계: 알고리즘별 기준을 선택함 — 피벗(Quick), 중간점(Merge), 인접 쌍(Bubble) 등
- 3단계: 선택한 전략에 따라 교환·삽입·병합을 수행함 — 분할정복(014 참조) 또는 반복
- 4단계: 부분 결과를 병합하거나 최종 정렬 배열을 반환함

> 요약: 입력 → 기준 선택 → 정렬 수행 → 결과 반환의 4단계로 동작함

## Ⅳ. 문제점
- 최악 복잡도 편차: Quick Sort는 피벗 선택이 편향되면 `O(n^2)`로 퇴화하여 성능 예측이 어려움
- 추가 메모리 소비: Merge Sort는 병합 시 `O(n)` 추가 공간이 필요하여 메모리 제약 환경에서 사용이 제한됨
- 안정성-성능 상충: in-place이면서 안정적이고 `O(n log n)`을 보장하는 비교 기반 정렬이 존재하지 않음

> 요약: 최악 복잡도·메모리·안정성 세 조건을 동시에 만족하는 비교 정렬은 현재까지 없음

## Ⅴ. 개선방안
1. 단기: 피벗을 median-of-three 등으로 선택하여 Quick Sort의 최악 퇴화를 방지함
2. 중기: 하이브리드 정렬(TimSort 등)을 적용하여 소규모 구간은 Insertion, 대규모는 Merge로 처리함
3. 장기: 데이터 분포에 따라 비교 기반과 비비교 기반(Radix, Counting)을 자동 선택하는 적응형 정렬 프레임워크를 도입함

> 요약: 피벗 전략 개선, 하이브리드 정렬, 적응형 선택으로 정렬 성능과 안정성을 동시에 확보함

## Ⅵ. 전망
- 발전 방향: GPU 병렬 정렬, 외부 정렬(External Sort) 등 대규모 데이터 처리용 정렬 기법이 확대됨
- 기술사적 판단: 정렬은 알고리즘 설계의 기본 패턴을 학습하는 핵심 주제이며 실무 최적화의 출발점임
- 기술사 제언: 데이터 특성(크기, 분포, 메모리 제약)에 맞는 정렬 전략을 근거와 함께 제시할 필요
