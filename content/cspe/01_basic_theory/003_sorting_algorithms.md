## 핵심 답안

정렬 알고리즘은 원소를 키 기준 순서로 재배열해 탐색, 병합, 집계, 중복 제거 같은 후속 처리를 가능하게 하는 기본 알고리즘이며, 기술사 답안에서는 평균 시간만이 아니라 **최악 시간**, **안정성**, **제자리성**, **입력 분포**, **외부 저장장치 사용 여부**를 기준으로 비교해야 함.

```text
요구사항(키/안정성/메모리) -> 정렬 방식 선택 -> 비교·이동 수행 -> 정렬 결과 검증
```

## 알고리즘별 선택 기준

| 구분 | 평균/최악 시간 | 공간 | 안정성 | 선택 기준 |
|:---|:---|:---|:---|:---|
| 퀵 정렬 | 평균 `O(n log n)`, 최악 `O(n^2)` | 재귀 스택 | 기본 불안정 | 평균 성능, 캐시 효율, 내부 정렬 |
| 병합 정렬 | 항상 `O(n log n)` | 추가 버퍼 필요 | 안정 정렬 가능 | 안정성, 외부 정렬, 예측 가능한 시간 |
| 힙 정렬 | 항상 `O(n log n)` | 제자리 가능 | 기본 불안정 | 메모리 제한, 최악 시간 보장 |
| 버블 정렬 | `O(n^2)` | 제자리 가능 | 안정 구현 가능 | 교육용, 매우 작은 데이터, 개념 설명 |

퀵 정렬은 평균 성능이 좋아 실무 라이브러리의 기반으로 자주 쓰이지만, 피벗 편향을 방치하면 최악 시간이 나빠지므로 무작위 피벗이나 인트로소트 같은 보완이 필요함.

## 비교 축

| 판단 축 | 질문 | 기술사적 의미 |
|:---|:---|:---|
| 시간 복잡도 | 평균뿐 아니라 최악을 보장해야 하는가 | 실시간·배치 마감·장애 상황 판단 |
| 안정성 | 같은 키의 기존 순서가 유지되어야 하는가 | 거래 로그, 다중 키 정렬, 사용자 목록 품질 |
| 공간 사용 | 추가 버퍼를 감당할 수 있는가 | 메모리 제한, 외부 정렬, 임베디드 환경 |
| 입력 분포 | 이미 정렬, 역정렬, 중복 키가 많은가 | 피벗 편향, 하이브리드 정렬 선택 |
| 저장 위치 | 메모리 내부인가, 디스크/분산 저장소인가 | 외부 병합 정렬, 파티션 정렬 선택 |

정렬 답안은 "어떤 알고리즘이 빠르다"가 아니라 "어떤 제약에서 어떤 비용을 감수하고 선택한다"로 써야 함.

## 절차 관점

1. **요구 조건 확인**: 키, 다중 키 여부, 안정성, 데이터 크기, 메모리 한계, 최악 시간 보장 필요성을 정함
2. **후보 알고리즘 선정**: 평균 성능은 퀵, 안정성과 외부 정렬은 병합, 메모리와 최악 보장은 힙처럼 후보를 좁힘
3. **비교 함수 설계**: 반사성, 반대칭성, 추이성, 동등 키 정책을 명확히 함
4. **정렬 수행 및 검증**: 전체 순서, 중복 키 순서, 메모리 피크, 최악 입력 성능을 확인함

```text
데이터 특성 + 요구 품질
        |
        v
정렬 방식 선택 -> 비교 함수 -> 원소 재배치 -> 정렬성/안정성 검증
```

## 오해와 감점 포인트

- **버블 정렬 일반화**: 버블 정렬은 설명용으로 적합할 뿐 대량 데이터의 실무 선택지로 쓰기 어려움
- **퀵 정렬 최악 누락**: 평균 `O(n log n)`만 쓰고 피벗 편향 시 `O(n^2)`를 빼면 비교 답안이 약함
- **안정성 누락**: 다중 키 정렬에서는 안정성이 결과 의미를 바꿀 수 있음
- **비교 함수 오류 누락**: 비교 기준이 추이성을 깨면 알고리즘이 맞아도 결과가 비결정적으로 보일 수 있음
- **외부 정렬 미고려**: 데이터가 메모리를 넘으면 내부 정렬 복잡도만으로는 답이 부족함

## 실무 적용 판단

| 상황 | 권장 판단 |
|:---|:---|
| 일반 메모리 내부 정렬 | 퀵 정렬 변형 또는 하이브리드 정렬을 우선 검토 |
| 안정성이 중요한 로그·거래 정렬 | 병합 정렬 또는 안정 정렬 라이브러리 선택 |
| 메모리 여유가 작고 최악 시간이 중요 | 힙 정렬 또는 인트로소트 검토 |
| 대용량 파일·분산 데이터 | 외부 병합 정렬, 파티션 정렬, 샘플 정렬 검토 |
| 이미 거의 정렬된 데이터 | 삽입 정렬 계열 또는 Timsort 같은 적응형 정렬 검토 |

## 답안 작성 포인트

1. 정의는 "키 기준 순서 재배열을 통해 후속 처리 효율을 높이는 알고리즘"으로 씀
2. 퀵·병합·힙·버블을 시간, 공간, 안정성, 선택 조건 표로 비교함
3. 최악 시간과 안정성은 별도 축으로 반드시 언급함
4. 실무 판단에서는 내부 정렬과 외부 정렬을 구분함
5. 결론은 "정렬 선택은 평균 속도보다 데이터 특성, 안정성, 메모리, 최악 보장의 균형"으로 마무리함

> 기술사 관점에서 정렬 알고리즘 비교는 암기표가 아니라 데이터 파이프라인의 비용과 품질을 좌우하는 선행 설계 판단임.
