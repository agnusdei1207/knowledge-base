# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터를 지정된 기준(오름차순, 내림차순 등)에 따라 재배치하는 알고리즘들을 시간복잡도, 공간복잡도, 안정성 세 축으로 비교 분석함
- **왜 필요한가**: 이진 탐색(004)이나 B-Tree 기반 데이터베이스 인덱스는 데이터가 사전에 정렬되어 있음을 전제로 동작하므로, 선행되는 정렬 성능이 시스템 전체의 검색 속도를 결정한다.
- **핵심 직관**: 모든 정렬의 핵심 목표는 "원소 간의 비교와 교환 횟수를 어떻게 최소화할 것인가"이다. 데이터를 분할하여 공략할수록(퀵, 병합) 빠르고, 트리 구조(힙)를 활용하면 최악의 경우에도 방어가 가능하다.

## 핵심 용어 정리

정렬을 비교할 때 사용하는 **핵심 판정 기준 3가지**:

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 시간 복잡도 | 정렬을 완료할 때까지 원소를 비교하는 횟수 (평균과 최악) | 시험지 100장을 채점하는 데 걸리는 시간 |
| 안정성 (Stability) | 값이 같은 두 원소의 원래 입력 순서가 정렬 후에도 유지되는가 | "동점자일 경우 먼저 제출한 사람이 앞선다"는 규칙 유지 |
| In-place (제자리 정렬) | 정렬 시 별도의 임시 배열을 만들지 않고 기존 배열 내에서 스왑만으로 해결하는가 | 좁은 방 안에서 물건들을 밖으로 빼지 않고 자리만 바꾸기 |

위 3가지 축으로 본 **4대 비교 기반 정렬**:

| 정렬 | 방식 | 비유 |
|:---|:---|:---|
| 버블 정렬 | 인접한 두 원소를 짝지어 비교하고 스왑하는 과정을 반복 | 옆 사람과 끝없이 키 재보며 자리 바꾸기 |
| 퀵 정렬 | 피벗을 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽으로 나눈 후 재귀 반복 | "기준점(피벗)보다 작은 사람 다 왼쪽!" 분할 정복 |
| 병합 정렬 | 배열을 더 이상 쪼갤 수 없을 때까지 반씩 나눈 뒤 정렬하며 다시 합침 | 서류를 낱장으로 찢은 뒤, 다시 묶으면서 정리하기 |
| 힙 정렬 | 데이터를 완전 이진 트리로 구성한 뒤 최대(또는 최소)값을 하나씩 뽑아냄 | 토너먼트 대진표를 그려서 1등만 계속 뽑아내기 |

## 깊이 이해

### 분할 정복이 왜 기하급수적으로 빠른가 (퀵·병합의 원리)
- 퀵 정렬과 병합 정렬은 배열을 절반씩 나누는 과정을 반복한다. N개를 반씩 계속 쪼개면 쪼개지는 횟수(트리의 깊이)는 log N번이 된다.
- 각 깊이 단계마다 전체 원소 N개를 한 번씩 쭉 훑으면서 비교하므로 총 연산 횟수는 N × log N = O(N log N)이 된다.
- 10만 건 정렬 시, 버블 정렬(O(N²))은 약 100억 번 비교해야 하지만, 퀵·병합 정렬(O(N log N))은 약 170만 번이면 끝나 수천 배의 성능 차이가 난다.

### 퀵 정렬은 언제 최악의 성능(O(N²))으로 추락하는가
- 퀵 정렬은 피벗(기준값)이 배열을 정확히 반씩 나눌 때 O(N log N)을 보장한다.
- 하지만 오름차순으로 이미 정렬된 배열에서 하필 맨 첫 번째 원소를 피벗으로 잡으면, 작은 그룹은 0개, 큰 그룹은 N-1개로 극단적으로 불균형하게 나뉜다.
- 이 분할이 매번 반복되면 쪼개는 횟수(깊이)가 log N이 아니라 N이 되어버리므로, 연산량이 N × N = O(N²)으로 급락한다. 이를 막기 위해 실무에서는 3개 값의 중앙값을 피벗으로 잡는 기법(Median-of-three)을 쓴다.

### 안정성(Stability)이 실무에서 왜 중요한가
- 여러 컬럼(키)을 기준으로 다중 정렬을 할 때 안정성이 드러난다.
- 예를 들어 직원 목록을 '부서명'으로 1차 정렬한 뒤, 다시 '이름'으로 2차 정렬한다고 하자. 이때 2차 정렬 알고리즘이 안정 정렬(병합 정렬)이어야만, 앞서 맞춰둔 부서명 순서가 섞이지 않고 유지된다. 퀵 정렬이나 힙 정렬은 불안정 정렬이라 기존 순서를 흩트려버린다.

### 흔한 오해·주의점
- "가장 빠르니까 항상 퀵 정렬을 쓰면 된다"는 틀린 상식이다. 최악의 경우 O(N²) 지연과 불안정성 때문에, Java의 객체 정렬은 안정성이 보장되는 Timsort(병합 정렬 변형)를 기본으로 사용한다.

### 비교하지 않고 정렬하는 방법도 있다 (비교 기반 vs 분배 기반)
- 지금까지 다룬 버블·퀵·병합·힙은 원소 두 개를 직접 맞대어 크기를 비교한 뒤 순서를 정한다. 이런 방식을 **비교 기반 정렬**이라 부르며, 대소 비교만 가능하면 어떤 데이터든 정렬할 수 있는 대신, 이론적으로 O(N log N)보다 더 빨라질 수 없다는 수학적 하한선이 있다(비교 한 번으로 얻는 정보량 자체가 유한하기 때문).
- 반면 정렬할 값이 정수이고 범위가 좁다면, 값끼리 비교하지 않고 값을 그대로 배열의 인덱스로 써버리는 **분배 기반 정렬**을 쓸 수 있다. 대표 예가 계수 정렬(Counting Sort)이다. 학생 성적(0~100점)을 정렬한다면, 성적이 90점인 학생을 만날 때마다 그냥 "인덱스 90번 칸의 개수"를 1씩 늘리기만 하면 된다 — 서로 비교할 필요 자체가 없다. 전체 데이터를 한 번만 훑으면 끝나므로 O(N + k)이며, 여기서 k는 값의 범위(0~100이면 101)다.
- 이 방식은 k가 작을 때만 유리하다. 성적이 아니라 0~9,900,000처럼 범위가 넓은 값을 정렬하면 k가 N보다 훨씬 커져서 오히려 비교 기반 정렬보다 느려진다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 탐색 효율을 극대화하기 위해 시간·공간 제약 내에서 레코드를 재배열하는 기법임.
> 2. **가치**: O(N²)에서 O(N log N)으로의 복잡도 개선은 대용량 배치 처리 트랜잭션의 OOM(메모리 부족) 및 타임아웃을 직접 방어함.
> 3. **판단 포인트**: 정렬 안정성(Stability), 추가 메모리 요구량(In-place), 최악의 데이터 분포 시나리오를 축으로 실무 알고리즘을 스위칭해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정렬 알고리즘의 동작 메커니즘 인지 | 퀵(피벗 분할), 병합(결합), 힙(트리)의 동작 차이 | 실무에서 안 쓰는 버블 정렬 서술에 지면 낭비 |

> 요약: 정렬에는 단일 정답이 없으며, 데이터 크기와 가용 메모리 한계를 기준으로 알고리즘을 교체하는 설계 역량이 중요함.

## Ⅰ. 개요 및 필요성

- 정의: 데이터베이스 인덱스 탐색이나 이진 탐색 등 후행 처리를 위해 키(Key) 값을 기준으로 레코드 순서를 재배열하는 과정임
- 배경: 이진 탐색(O(log n)) 성능을 얻으려면 데이터 집합이 사전에 정렬되어 있음을 전제해야 함
- 필요성: 하둡(Hadoop) 등 분산 처리 시 Shuffle & Sort 단계의 성능이 전체 배치 잡(Job)의 처리량(Throughput)을 결정하므로 최적화가 필수임

## Ⅱ. 핵심 정렬 알고리즘 메커니즘

```text
정렬 요구사항 -> 가용 공간·안정성 분석 -> 분할정복(Quick/Merge) / 트리(Heap) / 교환(Bubble) 선택 -> 정렬 완료
```

| 알고리즘 | 동작 메커니즘 | 성능 제어 핵심 |
|:---|:---|:---|
| 퀵 (Quick) | 피벗 기준 좌(작음)/우(큼) 파티셔닝 후 재귀 호출 | 최악 방지를 위한 피벗 중앙값 선택 전략 (Median-of-three) |
| 병합 (Merge) | 최소 단위 분할 후, 별도 공간에서 대소 비교하며 병합 | 배열 복사를 위한 O(N) 크기의 외부 임시 메모리 확보 |
| 힙 (Heap) | 완전 이진 트리 구성 후 루트 노드 반복 추출 | 배열 인덱스 연산(부모 i, 자식 2i) 기반 In-place 처리 |
| 버블 (Bubble) | 인접한 두 원소를 스왑하여 최대값을 끝으로 밀어냄 | 패스마다 확정 원소가 1개씩 증가하나 실무 성능 미달 |

> 요약: 성능을 좌우하는 O(n log n) 알고리즘들은 분할 정복이나 트리 구조를 활용해 비교 횟수를 비약적으로 축소함.

## Ⅲ. 동작원리 및 피벗 분할 흐름도 (퀵 정렬 중심)

```text
원본 데이터 확보 -> 중간값 피벗 선택 -> 피벗 기준 좌우 파티셔닝 -> 좌/우 부분배열 재귀호출 -> 피벗 기준 결합
```

- 1단계 [피벗 선정]: 분할 불균형을 예방하기 위해 첫 요소, 중간 요소, 끝 요소 중 중앙값을 피벗으로 선정함
- 2단계 [파티셔닝]: 투 포인터를 이동하며 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 제자리 스왑함
- 3단계 [재귀 분할]: 좌우로 나뉜 두 개의 부분 배열에 대해 동일한 퀵 분할 로직을 재귀적으로 호출함
- 4단계 [정렬 확정]: 쪼개진 부분 배열의 크기가 1 이하가 되면 호출 스택이 반환되며 전체 배열 정렬이 확정됨

> 요약: 배열을 피벗 기준으로 반분(O(log n))하고 전체 요소를 비교(O(n))하여 평균 O(n log n) 속도를 달성함.

## Ⅳ. 비교 기반 vs 분배 기반 정렬 특성
- 하한선: 원소끼리 대소를 비교해 순서를 정하는 비교 기반 정렬(퀵·병합·힙)은 O(n log n)보다 빨라질 수 없다. 값을 인덱스로 바로 대응시켜 비교 자체를 없앤 분배 기반 정렬(계수 정렬)은 O(n + k)까지 단축된다(k = 값의 범위).
- 적용 조건: 비교 기반 정렬은 대소 비교만 가능하면 문자열·객체 등 어떤 타입도 정렬할 수 있다. 분배 기반 정렬은 정수처럼 범위가 좁은 값에만 쓸 수 있다.
- 트레이드오프: 비교 기반 정렬은 범용성이 높은 대신 O(n log n) 상한을 벗어나지 못한다. 분배 기반 정렬은 k 크기만큼 메모리를 더 써서 O(n)에 가까운 속도를 얻는다.

> 요약: 키 값의 범위가 좁은 정수 데이터는 계수 정렬로 O(n)에 근접시키고, 그 외 범용 데이터는 O(n log n) 비교 기반 정렬을 쓴다.

## Ⅴ. 심화 비교 및 적용 판단 (4대 정렬 지표)

| 구분 | 퀵 정렬 (Quick) | 병합 정렬 (Merge) | 힙 정렬 (Heap) |
|:---|:---|:---|:---|
| 시간 복잡도 (평균 / 최악) | O(n log n) / O(n²) | O(n log n) / O(n log n) | O(n log n) / O(n log n) |
| 공간 복잡도 (제자리 정렬 여부) | O(log n) (콜스택 공간) | O(n) (임시 메모리 필수) | O(1) (In-place 보장) |
| 안정성 (Stable 성질 유지) | 불안정 (Unstable) | 안정 (Stable) | 불안정 (Unstable) |
| 실무 채택 기준 | 단일 키 기준 범용 고속 정렬 | 다중 복합 키 기준 정렬 시 필수 | 메모리가 극도로 제약된 임베디드 |

> 요약: 속도는 퀵 정렬, 안정성은 병합 정렬, 메모리 제약 하의 성능 방어는 힙 정렬을 선택하여 트레이드오프를 해결함.

**주요 리스크·대응:**
- 퀵 정렬 O(n²) 성능 추락: 이미 정렬된 배열에서 피벗 분할이 극단적으로 쏠림 발생 → 재귀 깊이 초과 시 힙 정렬로 전환하는 Introsort 적용 (지표: 함수 호출 최대 깊이 측정)
- 병합 정렬 OOM 발생: 대용량 데이터 정렬을 위해 O(n)의 힙 메모리 추가 할당 임계치 초과 → 청크 단위로 쪼개는 외부 정렬(External Merge Sort) 수행 (지표: 프로세스 힙 메모리 할당량)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 하이브리드 표준 라이브러리 도입: Java의 객체 정렬은 병합과 삽입을 섞은 Timsort로 안정성을 확보하고, C++은 퀵과 힙을 섞은 Introsort로 최악 성능을 방어함
2. 대용량 데이터 외부 병합 정렬(External Merge Sort) 설계: RAM 16GB 서버에서 100GB 로그를 정렬할 때 메모리 크기로 청크를 분할 정렬 후 디스크 I/O로 병합함
3. 다중 컬럼 정렬 쿼리 통제: 부서명 1차 정렬 후 이름 2차 정렬 수행 시, 2차 정렬에 안정 정렬 속성을 띄는 병합 계열 알고리즘을 강제하여 앞선 순서 붕괴를 예방함

**결론 (2줄):**
- 기술사 판단: 단일 알고리즘의 이론적 성능보다 데이터의 정렬 상태와 메모리 제약에 따라 최적의 알고리즘을 스위칭하는 하이브리드 구조 적용이 필수임.
- 향후 방향: 단일 노드의 연산 한계를 넘기 위해 분할 정복을 병렬화하여 다중 GPU 코어에서 처리하는 병렬 정렬 프레임워크로 성능 한계를 극복함.
