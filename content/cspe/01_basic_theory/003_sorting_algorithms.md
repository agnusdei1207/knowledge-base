# 정렬 알고리즘 비교 - 퀵·병합·힙·버블 (Sorting Algorithms)

## 1. 정의 및 개념

정렬 알고리즘은 데이터를 특정 키 기준의 순서로 재배열하여 탐색, 병합, 집계, 중복 제거 같은 후속 처리를 효율화하는 기본 알고리즘이다.

| 구분 | 정의 | 핵심 기준 |
|---|---|---|
| **비교 정렬** | 원소 간 대소 비교로 순서를 결정하는 정렬 | 비교 횟수, `O(n log n)` 하한 |
| **안정 정렬** | 같은 키를 가진 원소의 기존 상대 순서를 유지 | 다중 키 정렬, 로그·거래 처리 |
| **제자리 정렬** | 입력 배열 외 큰 추가 공간을 사용하지 않음 | 메모리 제한 환경 |
| **외부 정렬** | 데이터가 메모리를 초과할 때 디스크 기반으로 수행 | 대용량 파일, DB 처리 |

## 2. 주요 정렬 알고리즘 비교

| 알고리즘 | 평균 시간 | 최악 시간 | 공간 | 안정성 | 주요 특징 |
|---|---:|---:|---:|---|---|
| **퀵 정렬** | `O(n log n)` | `O(n²)` | 재귀 스택 | 기본 불안정 | 평균 성능 우수, 캐시 친화적 |
| **병합 정렬** | `O(n log n)` | `O(n log n)` | `O(n)` | 안정 가능 | 예측 가능, 외부 정렬에 적합 |
| **힙 정렬** | `O(n log n)` | `O(n log n)` | `O(1)` | 불안정 | 제자리, 최악 시간 보장 |
| **버블 정렬** | `O(n²)` | `O(n²)` | `O(1)` | 안정 가능 | 교육용, 소규모·거의 정렬 데이터 |

비교 기반 정렬은 일반적으로 `O(n log n)` 수준이 실무 기준선이며, 버블 정렬은 대량 데이터 처리의 기본 선택지로 적합하지 않다.

## 3. 선택 기준

| 상황 | 적합한 선택 | 이유 |
|---|---|---|
| 평균 성능과 캐시 효율 중시 | 퀵 정렬 또는 하이브리드 정렬 | 실제 내부 정렬에서 빠른 편 |
| 안정성이 중요 | 병합 정렬, Timsort 등 안정 정렬 | 같은 키의 상대 순서 유지 |
| 메모리가 제한됨 | 힙 정렬 | 추가 배열 없이 최악 `O(n log n)` 보장 |
| 대용량 파일 정렬 | 외부 병합 정렬 | 순차 I/O와 병합 단계에 적합 |
| 이미 거의 정렬된 데이터 | 삽입 정렬 계열, Timsort | 기존 순서를 활용 가능 |

정렬 알고리즘 선택은 평균 시간보다 데이터 분포, 안정성, 메모리, 최악 시간 보장 여부가 더 중요할 수 있다.

## 4. 구조 및 주요 연산

**퀵 정렬**
- 피벗을 기준으로 작은 값과 큰 값을 분할
- 분할 정복 방식으로 부분 배열 재귀 정렬
- 피벗 편향 시 최악 `O(n²)` 발생

**병합 정렬**
- 배열을 절반으로 나누고 각각 정렬한 뒤 병합
- 안정 정렬 구현 가능
- 추가 버퍼 필요

**힙 정렬**
- 최대 힙 또는 최소 힙 구성
- 루트 원소를 반복적으로 꺼내 정렬
- 제자리 구현 가능하지만 캐시 효율은 퀵 정렬보다 낮을 수 있음

**버블 정렬**
- 인접 원소를 반복 비교·교환
- 구현은 단순하나 `O(n²)`로 비효율적

## 5. 심화 이슈 (기술사 포인트)

1. **퀵 정렬 최악 회피**
   - 무작위 피벗, median-of-three, 인트로소트(Introsort)로 `O(n²)` 위험 완화.

2. **안정성 요구**
   - 거래 시간, 로그 순서, 다중 키 정렬에서는 안정성이 결과 의미를 바꿀 수 있다.

3. **비교 함수 품질**
   - 반사성, 반대칭성, 추이성이 깨지면 정렬 결과가 비결정적으로 나타난다.

4. **메모리와 I/O**
   - 메모리를 초과하는 정렬은 알고리즘 시간보다 디스크 I/O 패턴이 더 중요하다.

5. **라이브러리 정렬**
   - 실무 언어의 정렬은 퀵·병합·삽입 등을 섞은 하이브리드 방식이 많아 입력 특성을 함께 봐야 한다.

## 6. 결론

정렬 알고리즘은 단순히 데이터를 오름차순으로 만드는 기능이 아니라 후속 처리 비용과 데이터 품질을 좌우하는 핵심 알고리즘이다. 기술사 답안에서는 퀵·병합·힙·버블의 시간복잡도만 나열하지 말고, 안정성·메모리·최악 보장·외부 정렬 가능성을 기준으로 선택 근거를 제시해야 한다.
