## 미리 알고가기

- 안정 정렬: 같은 키를 가진 원소의 기존 순서를 정렬 후에도 유지하는 정렬 방식임
- 제자리 정렬: 입력 배열 외에 큰 보조 배열을 거의 쓰지 않고 원소 위치를 바꾸는 정렬 방식임
- 피벗: 퀵 정렬에서 원소를 왼쪽과 오른쪽으로 나누는 기준값임

## Ⅰ. 개요

- **정의/개념**: 정렬은 원소를 키 기준 순서로 재배열해 탐색, 병합, 집계 같은 후속 연산을 효율화하는 알고리즘 군이며, 대표 방식으로 퀵, 병합, 힙, 버블 정렬이 있음
- **배경/필요성**: 데이터 규모가 커질수록 무질서한 입력은 검색, 병합, 집계 비용을 키우므로 입력 특성과 메모리 제약에 맞게 비교와 이동 비용을 통제할 필요가 있음

## Ⅱ. 특징

- 정렬 알고리즘은 평균 속도, 최악 속도, 추가 메모리, 동일 키 순서 보존 여부가 주요 판단 기준임
- 퀵 정렬은 평균 성능이 우수하지만 입력 편향에 따라 최악 성능이 급격히 나빠질 수 있음
- 병합 정렬은 동일 키 순서 보존과 일관된 $O(n \log n)$ 성능이 강점이지만 추가 메모리가 필요함
- 힙 정렬은 제자리 정렬과 최악 $O(n \log n)$ 보장이 가능하나 캐시 지역성과 상수 비용 측면에서는 불리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 평균 시간복잡도 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 최악 시간복잡도 | $O(n^2)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 추가 공간 | 작음 | 큼 | 작음 | 작음 |
| 동일 키 순서 보존 | 보장 어려움 | 보장 | 보장 어려움 | 보장 |
| 적합 환경 | 범용 메모리 정렬 | 대용량 안정 정렬 | 메모리 제약 환경 | 교육용, 소규모 단순 정렬 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 기준 키 | 숫자, 문자열, 시간 등 정렬 기준 값이며 비교 함수 정의가 정확해야 함 |
| 분할 구조 | 피벗 분할, 반분 분할, 힙 구성처럼 정렬 방식을 나누는 구조이며 복잡도와 캐시 효율을 결정함 |
| 교환 또는 병합 | 원소 위치를 바꾸거나 부분 결과를 합치는 과정이며 데이터 이동량이 실제 성능에 영향 줌 |
| 보조 메모리 | 임시 배열, 재귀 스택, 힙 구조 등이며 메모리 제약 환경에서 중요한 판단 기준임 |

```text
+-----------+     +-----------+     +---------------+     +-----------+
| 입력 데이터   | --> | 분할 구조    | --> | 비교/교환/병합   | --> | 정렬 결과   |
+-----------+     +-----------+     +---------------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 기준선정 | --> | 분할/구성 | --> | 정렬반복 | --> | 결과확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **기준선정**: 비교 키와 오름차순 또는 내림차순 기준을 정함
2. **분할/구성**: 퀵은 피벗으로 분할하고, 병합은 반씩 나누고, 힙은 우선순위 구조를 만듦
3. **정렬반복**: 부분 배열을 재귀 또는 반복으로 정렬함
4. **결과확정**: 병합 또는 교환을 마쳐 전체 순서를 완성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 이미 정렬된 데이터나 나쁜 피벗이 반복되면 퀵 정렬의 분할이 치우쳐 실행시간이 $O(n^2)$까지 늘어날 수 있음
   - 해결방안: 무작위 피벗이나 median-of-three 전략을 적용하고 편향 입력에서 실행시간으로 검증함
2. 문제: 병합 정렬의 메모리 사용량이 커 대용량 데이터에서 임시 배열이 부담이 될 수 있음
   - 해결방안: 외부 정렬이나 블록 단위 병합으로 메모리 사용량을 제어하고 피크 메모리, 디스크 I/O로 검증함
3. 문제: 동일 키의 기존 순서를 유지해야 하는데 불안정 정렬을 쓰면 업무 데이터의 결과 정합성이 깨질 수 있음
   - 해결방안: 업무 규칙상 순서 유지가 필요하면 안정 정렬을 사용하고 동일 키 레코드 순서로 검증함

## Ⅶ. 적용 사례

- 로그 배치 처리에서는 병합 정렬로 시간순 정렬과 동일 시각 레코드 순서를 함께 유지하며, 배치 시간과 정렬 정확도로 결과를 확인함
- 메모리 제한 장비에서는 힙 정렬로 추가 메모리 사용을 줄이며, 피크 메모리와 처리 지연으로 결과를 확인함
- 일반 서비스 백엔드에서는 평균 성능이 좋은 퀵 계열 정렬을 사용하며, 평균 응답시간과 편향 입력 성능으로 결과를 확인함

## Ⅷ. 결론

정렬 알고리즘은 평균 속도만으로 고르면 안 되며, 최악 성능과 메모리 사용량과 동일 키 순서 보존 요구를 함께 보고 정해야 함.
