## 미리 알고가기

- 안정 정렬: 같은 키를 가진 원소의 기존 순서를 유지하는 정렬임
- 제자리 정렬: 입력 배열 외에 큰 보조 배열을 거의 쓰지 않는 정렬임
- 피벗: 퀵 정렬에서 왼쪽과 오른쪽을 나누는 기준값임
- 힙: 부모와 자식 사이의 우선순위를 유지하는 완전 이진 트리 구조임

## Ⅰ. 개요

- **정의/개념**: 정렬은 원소를 키 기준 순서로 재배치해 탐색, 병합, 집계 같은 후속 처리를 쉽게 만드는 알고리즘 군임
- **배경/필요성**: 데이터가 무질서하면 원하는 값을 찾거나 범위를 묶는 비용이 커짐. 입력 규모, 메모리 한계, 동일 키 순서 보존 여부에 맞는 정렬 방식을 골라야 함

## Ⅱ. 특징

- 비교 횟수와 데이터 이동량이 함께 성능을 좌우함
- 같은 $O(n \log n)$ 정렬도 안정성, 보조 메모리, 최악 성능 보장이 다름
- 입력이 이미 정렬돼 있거나 한쪽으로 치우치면 일부 알고리즘은 성능이 크게 흔들림
- 대용량 정렬에서는 CPU 시간뿐 아니라 메모리 복사와 디스크 접근도 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 처리 방식 | 피벗 기준 분할 | 반으로 나눈 뒤 병합 | 힙에서 우선순위 원소 추출 | 인접 원소 반복 교환 |
| 평균 시간 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 최악 시간 | 피벗이 치우치면 $O(n^2)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 안정성 | 기본 구현은 불안정 | 안정 정렬 가능 | 기본 구현은 불안정 | 안정 정렬 가능 |
| 적합한 상황 | 메모리 내 범용 정렬 | 안정성과 외부 정렬 | 최악 성능 보장 | 작은 입력, 교육용 예시 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 키 | 원소 순서를 정하는 기준이며 비교 함수와 맞아야 함 |
| 분할 또는 선택 구조 | 퀵은 피벗, 병합은 부분 배열, 힙은 우선순위 구조를 사용함 |
| 데이터 이동 방식 | 교환, 복사, 병합 방식에 따라 실제 실행시간이 달라짐 |
| 보조 메모리 | 임시 배열과 재귀 스택이 필요한지에 따라 적용 환경이 달라짐 |

```text
+---------+     +-----------+     +---------+
| 입력 배열 | --> | 비교/분할 | --> | 정렬 결과 |
+---------+     +-----------+     +---------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 기준 선택 | --> | 부분 처리 | --> | 원소 이동 | --> | 완료 확인 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 정렬 기준 키와 정렬 방향을 정함
2. 알고리즘별 방식으로 입력을 나누거나 우선순위를 만듦
3. 원소를 교환하거나 병합해 순서를 맞춤
4. 전체 원소가 기준 순서를 만족하는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 로그 병합이나 다중 키 정렬에서 같은 키 순서가 의미를 가지면 안정 정렬 여부를 먼저 확인해야 함
2. 대용량 입력에서는 평균 시간만 보지 말고 최악 시간, 임시 메모리, 데이터 이동량을 함께 측정해야 함

## Ⅶ. 결론

- 정렬 알고리즘은 평균 속도만으로 고르지 말고 안정성, 최악 성능, 보조 메모리까지 함께 보고 선택해야 함
