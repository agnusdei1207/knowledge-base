# 📖 【암기용】 개념 완전 이해

> 목적: 정렬 알고리즘 비교를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터를 기준 키 순서로 재배열하는 알고리즘군
- **왜 필요한가**: 정렬은 검색·조인·중복 제거·랭킹·인덱스 생성의 전처리다. 알고리즘마다 시간·메모리·안정 정렬 여부가 달라 업무 조건별 선택이 필요하다.
- **핵심 직관**: 같은 O(n log n)이라도 메모리 O(n), 제자리 정렬, 최악 O(n^2), 안정성 여부가 선택을 가름함

## 깊이 이해
- **배경·문제의식**: 데이터가 1,000건이면 단순 정렬도 처리 가능하지만, 1억건 로그 정렬은 메모리와 디스크 I/O가 병목이 된다. 정렬 선택은 입력 크기·분포·메모리 예산의 함수임.
- **작동 원리**: 퀵정렬은 피벗 기준 분할, 병합정렬은 반씩 나눈 뒤 병합, 힙정렬은 최대/최소 힙에서 루트를 반복 추출, 버블정렬은 인접 원소 교환으로 정렬한다.
- **비유**: 퀵정렬은 기준자를 세워 좌우 줄을 나누는 방식, 병합정렬은 작은 묶음을 정렬한 뒤 차례대로 합치는 방식이다.
- **구체 예시**: n=1,000,000에서 O(n log2 n)은 약 2,000만 비교, O(n^2)은 10^12 비교로 온라인 요청 처리에는 부적합함.
- **흔한 오해·주의점**: 퀵정렬 평균은 O(n log n)이지만 피벗이 편향되면 최악 O(n^2). 외부정렬·안정정렬 요구에는 병합정렬이 맞는 경우가 많다.

## 연결 개념
- 분할 정복 — 퀵·병합정렬의 공통 설계 패턴
- 힙 자료구조 — 힙정렬과 우선순위 큐 기반
- 외부 정렬 — 메모리 초과 데이터 정렬

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정렬 알고리즘은 비교·교환·분할·병합·힙 연산으로 키 순서를 재배열하는 기본 알고리즘이다.
> 2. **가치**: 검색 비용을 O(n)에서 O(log n)으로 낮추고, 조인·중복 제거·랭킹 처리의 선행 조건을 제공한다.
> 3. **판단 포인트**: 평균/최악 시간, 추가 공간, 안정 정렬, 캐시 지역성, 외부정렬 가능성을 조건별로 비교해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 키 기준으로 데이터를 재배열하는 기법
- 배경: 정렬은 이진 탐색, DB 인덱스 생성, MapReduce shuffle, 로그 분석의 기반 연산임
- 필요성: 대량 데이터에서는 O(n log n) 알고리즘 선택과 메모리 O(1)/O(n) 차이가 처리시간·메모리 사용량을 좌우함

## Ⅱ. 구조 및 구성요소

```text
입력 배열 -> 비교 기준 -> 분할/선택 -> 교환/병합 -> 정렬 결과
             / Quick: pivot partition
             / Merge: split and merge
             / Heap: heapify and extract
```

| 구성요소 | 역할 | 대표 알고리즘 |
|:---|:---|:---|
| 비교 함수 | 정렬 기준 지정 | 오름차순·내림차순·복합키 |
| 분할/선택 | 문제를 부분 배열로 축소 | 퀵 피벗, 병합 반분 |
| 교환/병합 | 원소 위치 확정 | Swap, Merge |
| 보조 저장소 | 임시 배열·힙 유지 | 병합 O(n), 힙 O(1) |

> 요약: 정렬은 비교 기준, 부분 문제 분할, 원소 재배치, 보조 저장소 사용 방식으로 구성됨.

## Ⅲ. 동작원리 및 흐름도

```text
입력 수집 -> 정렬 조건 확인 -> 알고리즘 선택
        -> 비교·교환/병합 반복 -> 정렬 검증 -> 후속 검색/조인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 크기·분포 확인 | n, 중복률, 거의 정렬 여부 |
| 2 | 요구사항 식별 | 안정성, 메모리, 최악 시간 |
| 3 | 알고리즘 선택 | Quick/Merge/Heap/Bubble |
| 4 | 정렬 수행 | 비교 횟수, swap 횟수 |
| 5 | 결과 검증 | 인접 원소 key[i]≤key[i+1] |

> 요약: 입력 특성과 요구사항을 먼저 고정한 뒤 정렬 알고리즘을 선택하고 정렬 순서 불변식을 검증함.

## Ⅳ. 특징

| 구분 | 시간복잡도 | 공간복잡도 | 판단 포인트 |
|:---|:---|:---|:---|
| 퀵정렬 | 평균 O(n log n), 최악 O(n^2) | O(log n) 스택 | 캐시 지역성, 피벗 편향 주의 |
| 병합정렬 | O(n log n) | O(n) | 안정 정렬, 외부정렬 적합 |
| 힙정렬 | O(n log n) | O(1) | 최악 보장, 캐시 지역성 낮음 |
| 버블정렬 | O(n^2) | O(1) | 교육·소량 데이터 검증용 |

> 요약: 일반 메모리 정렬은 퀵, 안정성·외부정렬은 병합, 최악 보장과 O(1) 공간은 힙을 선택함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 정렬 알고리즘 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단순 교환 정렬 | Quick/Merge/Heap/TimSort | n=10^5 이상이면 O(n log n) 계열 |
| 비용/성능 | 평균 시간만 고려 | 최악 시간·공간·안정성 동시 비교 | 안정 정렬 필요 시 Merge/TimSort |
| 운영/위험 | 메모리 내 정렬 가정 | 외부정렬·분산정렬 포함 | 데이터가 RAM 70% 초과 시 외부정렬 |

> 요약: 정렬 선택은 평균 Big-O보다 안정성, 메모리, 최악 시간, 외부정렬 조건으로 결정된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 퀵정렬 최악 | 피벗 편향 | randomized pivot, introsort 전환 | recursion depth, 비교 횟수 |
| 메모리 초과 | 병합 보조 배열 O(n) | chunk 단위 외부정렬, k-way merge | RSS, spill file size |
| 데이터 skew | 분산 정렬 파티션 편차 | sampling partition, skew key 분리 | partition size p95/p50 |

> 요약: 정렬 리스크는 피벗 편향, 보조 메모리, 분산 skew이며 깊이·RSS·파티션 편차로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시간 | O(n log n) 알고리즘, p95 처리시간 목표 충족 | 벤치마크 |
| 공간 | RSS가 노드 메모리 80% 이하 | 프로파일러, OS metric |
| 정확도 | 정렬 불변식 100% 통과 | property-based test |

> 요약: 정렬 도입 효과는 처리시간, 메모리, 정렬 불변식 검증이 동시에 충족될 때 인정된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 메모리 내 정렬: n≤10^7, 랜덤 분포이면 introsort(Quick+Heap 전환)로 평균 O(n log n)과 최악 O(n log n) 확보
2. 안정 정렬: 다중 키 정렬·로그 타임라인은 merge sort 또는 TimSort 사용, 추가 메모리 O(n) 예산 반영
3. 대용량 정렬: 메모리 초과 데이터는 run 생성 후 k-way merge 외부정렬 적용, 디스크 I/O와 블록 크기 4MB~128MB 조정

**결론 (2줄):**
- 기술사 판단: 정렬 선택은 Big-O만이 아니라 안정성·메모리·입력 분포·최악 시간 보장 조건으로 결정해야 함
- 향후 방향: 분산 정렬은 샘플링 파티셔닝과 skew 완화로 셔플 데이터 편차를 줄이는 방향 필요
