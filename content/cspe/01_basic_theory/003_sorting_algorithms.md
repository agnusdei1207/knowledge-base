## 미리 알고가기

- 키: 정렬 순서를 결정하는 기준 값이며 숫자, 문자열, 날짜 등이 될 수 있음
- 안정 정렬: 같은 키를 가진 원소의 기존 상대 순서를 유지하는 정렬임
- 제자리 정렬: 입력 배열 외에 큰 추가 메모리를 사용하지 않는 정렬임
- 비교 정렬: 두 원소의 대소 비교만으로 순서를 결정하는 정렬 방식임
- 최악 복잡도: 특정 입력에서 가장 나쁜 수행시간을 기준으로 한 비용임

## Ⅰ. 개요

- **정의**: 정렬 알고리즘은 데이터를 키 기준 순서로 재배열해 탐색·병합·집계 같은 후속 처리를 가능하게 하는 기본 알고리즘 군임
- **배경/필요성**: 정렬은 단순히 오름차순 결과를 만드는 작업이 아니라 전체 데이터 처리 파이프라인의 비용과 품질을 좌우함. 특히 대량 데이터에서는 `O(n log n)` 여부, 안정성 요구, 외부 저장장치 사용 여부가 알고리즘 선택의 핵심임.
- **비유**: 책을 제목순으로 꽂을 때 빠르게 나누어 꽂을지, 임시 책상을 써서 병합할지, 우선순위 더미를 만들지 고르는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정렬 방식별 선택 기준 확인 | 시간 복잡도, 안정성, 제자리성, 입력 분포 | 장점 나열, 버블 정렬 일반 적용 |

> 요약: 정렬은 키 순서를 만드는 알고리즘이며, 데이터 특성과 운영 제약에 맞는 방식을 선택해야 함.

## Ⅱ. 특징/비교

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 평균 시간 | `O(n log n)`, 캐시 친화적임 | `O(n log n)`, 입력 분포 영향이 작음 | `O(n log n)` 보장 | `O(n^2)` |
| 최악 시간 | 피벗 편향 시 `O(n^2)` | 항상 `O(n log n)` | 항상 `O(n log n)` | `O(n^2)` |
| 메모리 | 재귀 스택 중심 | 병합용 추가 공간 필요 | 제자리 구현 가능 | 제자리 구현 가능 |
| 안정성 | 기본 구현은 불안정 | 안정 정렬 가능 | 기본 구현은 불안정 | 안정 구현 가능 |
| 선택 조건 | 평균 성능과 캐시 효율 중시 | 안정성, 외부 정렬, 예측 가능성 중시 | 메모리 제한과 최악 보장 중시 | 교육, 거의 정렬된 소규모 검증 |

> 요약: 정렬 선택은 낮은 평균 비용만이 아니라 최악 보장, 안정성, 메모리 제약을 함께 보는 판단임.

- 대규모 범용 정렬은 보통 퀵 정렬 변형이나 팀소트처럼 입력 특성을 활용한 혼합 방식이 쓰임
- 안정성이 필요한 로그, 거래, 다중 키 정렬에서는 병합 계열이 유리함
- 버블 정렬은 개념 설명용으로 적합하나 운영 데이터 처리의 기본 선택지는 아님

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력배열 | ---> | 비교/교환| ---> | 정렬결과 |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 정렬키   |      | 전략선택 |      | 안정성   |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 데이터 | 정렬 대상 레코드 집합이며 크기와 분포가 비용을 결정함 | 책 더미 |
| 정렬 키 | 원소 간 순서를 판단하는 기준 값이며 다중 키일 수 있음 | 책 제목 라벨 |
| 비교 함수 | 두 원소의 선후 관계를 결정하고 전체 정렬의 일관성을 보장함 | 정리 규칙 |
| 재배치 전략 | 분할, 병합, 힙 구성, 인접 교환처럼 원소를 움직이는 방식임 | 책장 정리 방식 |
| 보조 공간 | 병합 버퍼, 재귀 스택, 힙 구조 등 추가로 필요한 저장공간임 | 임시 책상 |

> 요약: 정렬은 키와 비교 규칙을 기준으로 원소를 재배치하고, 전략별 시간·공간 비용이 달라지는 구조임.

- 비교 함수가 추이성을 만족하지 않으면 어떤 알고리즘도 올바른 전체 순서를 보장하기 어려움
- 정렬 대상이 메모리를 초과하면 외부 정렬처럼 저장장치 접근 구조를 따로 설계해야 함
- 안정성은 구성요소 표에는 품질 속성으로 보이지만 실제 업무에서는 결과 의미를 바꾸는 요구사항임

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 요구확인 | ---> | 방식선택 | ---> | 재배치   | ---> | 검증반환 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 키/안정성|      | 비용판단 |      | 비교/교환|      | 순서확인 |
+----------+      +----------+      +----------+      +----------+
```

1. **요구 식별** - 데이터 크기, 키, 안정성, 메모리 한도, 최악 시간 보장 필요성을 확인함
2. **알고리즘 선택** - 평균 성능은 퀵, 안정성은 병합, 메모리 제약은 힙처럼 선택 기준을 매핑함
3. **정렬 수행** - 선택한 방식의 비교, 교환, 병합, 힙 조정을 통해 원소 순서를 재배치함
4. **결과 검증** - 전체 순서, 중복 키의 상대 순서, 메모리 사용량, 수행시간을 확인함

> 요약: 정렬 절차는 요구 조건을 먼저 고정하고 그 조건에 맞는 재배치 전략을 적용하는 흐름임.

- 다중 키 정렬은 낮은 우선순위 키부터 안정 정렬을 적용하거나 비교 함수를 명확히 작성해야 함
- 이미 거의 정렬된 데이터는 삽입 정렬 계열이나 하이브리드 정렬이 더 나을 수 있음
- 병렬 정렬은 분할과 병합 단계의 동기화 비용까지 고려해야 함

## Ⅴ. 문제점

- **P1 최악 입력 취약성**: 퀵 정렬은 피벗 선택이 편향되면 분할 균형이 깨져 `O(n^2)`로 악화될 수 있음
- **P2 안정성·메모리 트레이드오프**: 병합 정렬은 안정성과 예측 가능한 시간을 제공하지만 추가 버퍼가 필요해 메모리 제한 환경에서 부담이 됨
- **P3 잘못된 비교 함수**: 비교 기준이 일관되지 않거나 동등 키 처리가 불명확하면 정렬 결과가 비결정적으로 보일 수 있음

> 요약: 정렬의 실패 지점은 알고리즘 자체보다 입력 분포, 메모리 조건, 비교 규칙에서 자주 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 무작위 피벗, median-of-three, 깊이 제한 후 힙 정렬 전환 같은 인트로소트 전략을 적용함 (확인: 최악 입력 테스트)
- **P2 대응**: 안정성이 필수인 경우 메모리 예산을 확보하고, 필수가 아니면 힙·퀵 계열로 전환함 (확인: 보조 공간 사용량)
- **P3 대응**: 비교 함수의 반사성, 반대칭성, 추이성을 단위 테스트하고 동등 키 정책을 명시함 (확인: 중복 키 테스트셋)

> 요약: 정렬 개선은 피벗·메모리·비교 규칙을 요구사항에 맞게 통제하는 방향으로 수행해야 함.

## Ⅶ. 전망

- **발전 방향**: 대규모 데이터 처리에서는 내부 정렬보다 분산 정렬, 외부 정렬, 컬럼형 저장소의 정렬 키 설계가 중요해짐
- **기술사적 판단**: 평균 복잡도만으로 선택하지 말고 안정성, 메모리, 최악 시간, 데이터 분포를 선택 기준으로 제시해야 함
- **기술사 제언**: 답안에서는 퀵·병합·힙·버블을 단순 암기표로 쓰기보다 어떤 조건에서 배제하거나 채택하는지 설명해야 함
