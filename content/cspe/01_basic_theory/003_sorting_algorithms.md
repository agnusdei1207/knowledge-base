## 미리 알고가기

- 안정 정렬(Stable Sort): 동일 키 원소의 입력 순서가 정렬 후에도 유지되는 성질임
- 제자리 정렬(In-place Sort): 입력 배열 외 추가 메모리를 거의 쓰지 않는 성질임
- 피벗(Pivot): 퀵 정렬에서 작은 값과 큰 값을 나누는 기준 원소임
- 힙(Heap): 부모 키가 자식 키보다 크거나 작은 완전 이진 트리형 우선순위 구조임
- 입력 크기 $n$: 정렬할 전체 원소 수이며 시간·공간복잡도의 기준 변수임

## 작성 근거(검토용)

- **방향성**: 비교 기반 정렬은 $\Omega(n \log n)$ 하한을 넘을 수 없으므로, 안정성·메모리 여유 조건에 맞춰 병합 정렬과 퀵·힙 정렬 중 하나를 고르고 최악 상황은 피벗 무작위화나 정렬 전환으로 막아야 함
- **개요 구성**: 정렬 결과가 후속 연산의 기준 순서가 된다는 점을 넣어 단순 재배열 설명을 피함
- **Ⅱ. 특징 선정**: 비교 기반 한계, 안정성, 보조 공간, 입력 분포는 알고리즘 선택을 직접 바꿈
- **Ⅲ. 비교축 선정**: 처리 방식, 최악 시간, 주요 제약은 네 정렬의 실행 비용과 오적용 위험을 가르며, 버블 정렬은 비교 대상에는 포함하되 실무 적용성은 낮아 원리 확인용으로만 다룸
- **Ⅳ. 구조 선정**: 정렬 키·처리 구간·재배열 연산은 정렬 결과를 만드는 핵심이고, 보조 공간과 동일 키 순서는 공간 비용과 안정성을 결정함
- **Ⅴ. 절차 선정**: 알고리즘별 분할·구성·교환 절차는 Ⅱ·Ⅲ이 제시한 편향 분할·불안정성 판단의 동작 근거임
- **Ⅵ. 실무 사례 선정**: 피벗 무작위화와 안정 정렬 선택은 성능·결과 순서·메모리 검증을 실제 서비스로 연결함
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 하한·안정성 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 정렬 알고리즘은 원소를 키 기준 순서로 재배열해 탐색·병합·집계 같은 후속 연산의 기준 순서를 만드는 알고리즘 군임
- **배경/필요성**: 입력 조건별 지연과 결과 안정성을 확보하기 위해 정렬 방식 선택 기준이 필요함

### 쉽게 이해하기 (학습용)
- 물건을 크기순으로 줄 세워 놓아야 나중에 원하는 물건을 빨리 찾거나 짝을 맞춰 정리할 수 있는 것과 같음

## Ⅱ. 특징

- 비교 기반 정렬은 키 비교만으로 순서를 정하며 일반 비교 모델에서 $\Omega(n \log n)$ 하한을 가짐
- 안정 정렬은 동일 키의 입력 순서를 보존해 다중 키 정렬 결과를 예측 가능하게 함
- 재귀로 구현한 제자리 정렬은 호출 스택만큼 추가 공간을 씀
- 입력의 초기 순서와 피벗 편향은 퀵 정렬의 분할 균형과 재귀 깊이를 바꿔 실제 지연에 영향을 줌

### 쉽게 이해하기 (학습용)
- 카드를 비교만으로 정렬하면 아무리 잘해도 어느 수준 이하로는 빨라지지 않음
- 같은 점수의 카드끼리 원래 순서를 그대로 두는 방식도 있고 뒤섞이는 방식도 있음
- 카드를 나누는 기준(피벗)을 잘못 고르면 한쪽에 카드가 몰려 정리가 오히려 느려짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 (Quick) | 병합 정렬 (Merge) | 힙 정렬 (Heap) | 버블 정렬 (Bubble) |
|:---|:---|:---|:---|:---|
| **처리 방식** | 피벗 기준 제자리 분할 | 반으로 분할한 뒤 병합 | 힙 구성 후 루트 추출 | 인접 원소 교환 |
| **최악 시간** | $O(n^2)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| **주요 제약** | 편향 분할 시 $O(n^2)$ 퇴화 | $O(n)$ 보조 배열 필요 | 동일 키의 입력 순서 미보존 | 인접 교환으로 최대 $O(n^2)$번 쓰기 |

> 요약: 퀵 정렬은 편향 분할, 병합 정렬은 보조 배열, 힙 정렬은 불안정성, 버블 정렬은 이차 쓰기 비용이 주요 제약임.

### 쉽게 이해하기 (학습용)
- 카드 더미를 기준 카드로 나누는 방법(퀵), 반씩 쪼개 합치는 방법(병합), 제일 큰 카드부터 뽑아내는 방법(힙), 옆 카드와 계속 바꿔치기하는 방법(버블)은 저마다 속도와 필요한 여유 공간이 다름

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 정렬 키·비교 함수 | 원소의 목표 순서와 동등 키를 판정하는 기준 |
| 처리 구간 | 비교·분할·병합을 적용할 입력 또는 부분열의 범위 |
| 재배열 연산 | 교환·이동·병합으로 원소 위치를 바꾸는 연산 |
| 보조 공간 | 임시 배열과 재귀 호출 정보에 필요한 추가 저장 공간 |
| 안정성 조건 | 동일 키 원소의 입력 순서를 정렬 후에도 보존하는 조건 |

```text
[ 정렬 처리 구조 ]
+----------+      +----------+      +----------+      +----------+
| 입력 원소 | ---> | 키 비교  | ---> | 이동/병합 | ---> | 정렬 결과 |
+----------+      +----------+      +----------+      +----------+
                       |
                       v
                 안정성·공간 제약
```

> 요약: 정렬 알고리즘은 키 비교로 처리 구간의 원소를 재배열하며 보조 공간과 동일 키 순서 보존 여부가 구현을 가름함.

### 쉽게 이해하기 (학습용)
- 어떤 기준으로 비교할지(정렬 키), 어디까지를 정리할지(처리 구간), 실제로 자리를 바꾸는 동작(재배열)이 맞물려 정렬을 완성하고, 이 과정에서 빌리는 여유 공간(보조 공간)의 크기가 방식마다 다름

## Ⅴ. 원리 및 절차 흐름도

```text
퀵 정렬: 피벗 선정 -> 작은값·큰값 분할 -> 좌우 부분열 재귀
병합 정렬: 절반 분할 -> 좌우 부분열 재귀 정렬 -> 두 부분열 병합
힙 정렬: 최대 힙 구성 -> 루트·말단 교환 -> 힙 크기 축소 후 재구성
버블 정렬: 인접 비교 -> 교환 -> 패스 범위 축소
```

1. **퀵 정렬**: 피벗보다 작은 값과 큰 값으로 원소를 나눈 뒤 좌우 부분열을 재귀 정렬함
2. **병합 정렬**: 배열을 절반씩 재귀 분할한 뒤 정렬된 두 부분열을 순서대로 병합함
3. **힙 정렬**: 최대 힙을 구성한 뒤 루트와 말단을 교환하고 힙 크기를 줄여 재구성을 반복함
4. **버블 정렬**: 인접 원소를 비교·교환하며 패스마다 정렬 범위를 하나씩 줄임

> 요약: 네 정렬은 분할·구성 방식은 다르지만 비교 결과에 따른 교환·병합을 반복해 정렬을 완성함.

### 쉽게 이해하기 (학습용)
- 네 가지 정리법은 카드를 나누고, 합치고, 뽑고, 맞바꾸는 방법은 다르지만 결국 비교한 결과대로 자리를 바꾸는 동작을 반복한다는 점은 같음

## Ⅵ. 실무 사례

1. 검색 랭킹 배치는 피벗을 무작위화한 퀵 정렬을 적용하고, 재귀 깊이가 한도를 넘으면 힙 정렬로 전환함
2. 정산 원장 출력은 병합 정렬로 동일 시각 거래의 입력 순서를 보존함

### 쉽게 이해하기 (학습용)
- 대량의 순위를 매길 때는 빠른 방법(퀵)을 쓰다가 문제가 생기면 안전한 방법(힙)으로 바꾸고, 거래 내역처럼 순서가 중요한 자료는 원래 순서를 지켜주는 방법(병합)을 쓰는 것과 같음

## Ⅶ. 결론

- 비교 기반 정렬은 $\Omega(n \log n)$ 하한을 넘을 수 없으므로, 안정성과 메모리 여유 조건에 맞춰 병합·퀵·힙 중 하나를 선택해야 함
- 동일 키의 순서 보존 여부와 최악 지연을 먼저 확인하고, 데이터가 메모리를 넘으면 외부 정렬로 전환해야 함

### 쉽게 이해하기 (학습용)
- 정리할 공간과 짐의 특성(이미 어느 정도 정리돼 있는지, 같은 물건끼리 순서를 지켜야 하는지)에 따라 방법을 다르게 골라야 하고, 방 안에 다 못 넣을 만큼 짐이 많으면 아예 다른 방식(외부 정렬)을 써야 함
