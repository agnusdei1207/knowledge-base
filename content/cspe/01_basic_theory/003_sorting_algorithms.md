## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 데이터 집합을 특정 기준(오름차순·내림차순)으로 재배열하는 알고리즘 군으로, 비교 기반과 비비교 기반으로 분류됨 |
| **배경/필요성** | 탐색·병합·중복 제거 등 후속 연산의 전제 조건이며, 정렬 알고리즘 선택이 전체 시스템 성능을 좌우함 |
| **출제 의도** | 주요 정렬 알고리즘의 시간·공간 복잡도를 비교하고, 상황별 선택 기준을 설명할 수 있는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 비교기반  | --> | 분할정복  | --> | 비비교   |
| (Bubble/ |     | (Quick/  |     | (Counting|
|  Insert) |     |  Merge)  |     |  /Radix) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 버블/삽입 정렬 | 인접 원소를 반복 비교·교환하며, O(n²)이나 소규모·거의 정렬된 데이터에 적합함 | 카드 한 장씩 끼워넣기 |
| 퀵/병합/힙 정렬 | 분할 정복 기반 O(n log n) 알고리즘으로, 대규모 데이터 정렬의 표준임 | 묶음을 나눠서 각각 정리 |
| 계수/기수 정렬 | 비교 없이 키 값의 분포를 이용하며, 정수 범위 제한 시 O(n+k)로 선형 정렬함 | 우편물 번호별 분류함 |

> 요약: 비교 기반(O(n log n) 하한)과 비비교 기반(선형)으로 구분되며, 데이터 특성에 따라 선택함.

## Ⅲ. 절차
```
+------------+     +------------+
| 피벗선택   | --> | 분할       |
| (Quick)    |     | (Partition)|
+------------+     +------------+
                        |
+------------+     +----+-------+
| 정렬완료   | <-- | 재귀정렬  |
|            |     | (좌·우)   |
+------------+     +------------+
```

1. 피벗 선택: 배열에서 기준 원소(피벗)를 선택함(중앙값·랜덤 등)
2. 분할(Partition): 피벗보다 작은 원소는 좌측, 큰 원소는 우측으로 재배치함
3. 재귀 정렬: 좌·우 부분 배열에 대해 동일 과정을 재귀 적용함
4. 병합·완료: 분할된 배열이 합쳐져 전체 정렬이 완성됨(퀵은 In-place, 병합은 별도 배열 사용)

> 요약: 피벗 선택 → 분할 → 재귀 정렬 → 병합으로 O(n log n) 정렬을 수행함.

## Ⅳ. 문제점
- 퀵 정렬 최악 O(n²): 이미 정렬된 데이터에서 피벗이 최솟/최댓값이면 분할이 편향됨
- 병합 정렬 공간 O(n): 별도 배열이 필요하여 메모리 제약 환경에서 부적합함
- 불안정 정렬: 힙·퀵 정렬은 동일 키 원소의 상대 순서(안정성)를 보장하지 않음

## Ⅴ. 개선방안
- (단기) 랜덤 피벗·3중 중앙값: 퀵 정렬의 최악 사례 확률을 줄임
- (중기) Timsort 적용: 삽입+병합 혼합으로 실 데이터의 부분 정렬을 활용하여 O(n log n) 보장 + 안정성 확보함
- (장기) 외부 정렬·병렬 정렬: 메모리 초과 데이터는 디스크 기반 외부 정렬, GPU 병렬 정렬을 적용함

## Ⅵ. 전망
- Python·Java 표준 라이브러리에 Timsort가 채택되었으며, GPU 기반 병렬 정렬(Radix Sort on GPU)이 대규모 데이터 처리의 표준으로 확산될 전망임
