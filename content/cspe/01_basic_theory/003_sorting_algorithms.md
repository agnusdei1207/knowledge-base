## 미리 알고가기

- 안정성: 같은 키를 가진 원소의 기존 순서를 정렬 후에도 유지하는 성질임
- 제자리 정렬: 입력 배열 외 추가 메모리 사용을 최소화하는 정렬 방식임
- 피벗: 퀵 정렬에서 분할 기준이 되는 원소임

## Ⅰ. 개요

- **정의/개념**: 정렬은 원소를 키 기준 순서로 재배열해 탐색, 병합, 집계 같은 후속 연산을 효율화하는 알고리즘 군이며, 대표 방식으로 퀵, 병합, 힙, 버블 정렬이 있음
- **배경/필요성**: 데이터 처리는 결국 검색과 비교 비용을 줄이는 방향으로 수렴하므로, 입력 규모와 메모리 제약에 맞는 정렬 방식 선택이 전체 시스템 지연시간을 좌우함

## Ⅱ. 특징

- 정렬 알고리즘은 평균 속도, 최악 속도, 추가 메모리, 안정성 여부가 주요 선택 기준임
- 퀵 정렬은 평균 성능이 우수하지만 입력 편향에 따라 최악 성능이 급격히 나빠질 수 있음
- 병합 정렬은 안정성과 일관된 $O(n \log n)$ 성능이 강점이지만 추가 메모리가 필요함
- 힙 정렬은 제자리 정렬과 최악 $O(n \log n)$ 보장이 가능하나 캐시 지역성과 상수 비용 측면에서는 불리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 평균 시간복잡도 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 최악 시간복잡도 | $O(n^2)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| 추가 공간 | 작음 | 큼 | 작음 | 작음 |
| 안정성 | 불안정 | 안정 | 불안정 | 안정 |
| 적합 환경 | 범용 메모리 정렬 | 대용량 안정 정렬 | 메모리 제약 환경 | 교육용, 소규모 단순 정렬 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 기준 키 | 숫자, 문자열, 시간 등 정렬 기준 값이며 비교 함수 정의가 정확해야 함 |
| 분할 구조 | 피벗 분할, 반분 분할, 힙 구성 등 방식 차이가 남 구조가 복잡도와 캐시 효율을 결정함 |
| 교환 또는 병합 | 원소 위치를 바꾸거나 부분 결과를 합침 데이터 이동량이 실제 성능에 영향 줌 |
| 보조 메모리 | 임시 배열, 재귀 스택, 힙 구조 등이며 메모리 제약 환경에서 중요한 판단 기준임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 기준선정 | --> | 분할/구성 | --> | 정렬반복 | --> | 결과확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **기준선정**: 비교 키와 오름차순 또는 내림차순 기준을 정함
2. **분할/구성**: 퀵은 피벗으로 분할하고, 병합은 반씩 나누고, 힙은 우선순위 구조를 만듦
3. **정렬반복**: 부분 배열을 재귀 또는 반복으로 정렬함
4. **결과확정**: 병합 또는 교환을 마쳐 전체 순서를 완성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 편향 입력에서 퀵 정렬이 퇴화해 이미 정렬된 데이터나 나쁜 피벗 선택은 $O(n^2)$을 유발함
   - 해결방안: 무작위 피벗이나 median-of-three 전략을 적용하고 편향 입력 성능로 검증함
2. 문제: 병합 정렬의 메모리 사용량이 커 대용량 데이터에서 임시 배열이 부담이 될 수 있음
   - 해결방안: 외부 정렬이나 블록 단위 병합으로 메모리 사용량을 제어하고 피크 메모리, 디스크 I/O로 검증함
3. 문제: 안정성 요구를 무시한 선택이 발생해 동일 키 순서가 중요한 업무 데이터에서는 결과 정합성이 깨질 수 있음
   - 해결방안: 업무 규칙상 순서 유지가 필요하면 안정 정렬을 우선 선택하고 동일 키 레코드 순서로 검증함

## Ⅶ. 적용 사례

- 로그 배치 처리: 병합 정렬로 시간순 정렬과 동일 시각 레코드 순서를 함께 유지함, 확인 지표는 배치 시간과 정렬 정확도임
- 메모리 제한 장비: 힙 정렬로 추가 메모리 사용을 줄임, 확인 지표는 피크 메모리와 처리 지연임
- 일반 서비스 백엔드: 평균 성능이 좋은 퀵 계열 정렬을 사용함, 확인 지표는 평균 응답시간과 편향 입력 성능임

## Ⅷ. 결론

정렬 알고리즘은 속도만으로 고를 수 없고 최악 성능, 메모리, 안정성 요구를 함께 따져 데이터 특성과 운영 조건에 맞는 방식을 선택해야 함.
