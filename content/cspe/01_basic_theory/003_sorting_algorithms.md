## Ⅰ. 개요
- **정의**: 데이터 집합을 특정 기준(오름차순 등)에 따라 재배치하는 알고리즘
- **배경/필요성**: 탐색·병합·중복 제거 등 후속 연산의 전제조건이 정렬이며, 정렬 방식에 따라 전체 시스템 응답 시간이 좌우됨
- **비유**: 도서관에서 책을 제목 순으로 꽂아두면 원하는 책을 빨리 찾을 수 있는 것과 동일함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘별 시간·공간 복잡도 비교 능력 | 최선·평균·최악 복잡도 구분(001 참조) | 안정성(Stable) 여부를 빠뜨리지 않을 것 |

> 요약: 정렬은 후속 연산의 전제이며, 알고리즘마다 복잡도·안정성이 다름

## Ⅱ. 구성요소
```text
       +------------------+
       |   정렬 알고리즘   |
       +--------+---------+
                |
    +-----------+-----------+
    |           |           |
+---+---+  +---+---+  +----+----+
| 비교형 |  | 비교형 |  | 비교형  |
| 교환   |  | 분할   |  | 선택   |
+---+---+  +---+---+  +----+----+
    |          |            |
  버블      퀵/병합        힙
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 버블 정렬 | 인접 원소를 반복 비교·교환하여 큰 값을 끝으로 밀어냄 | 탄산 거품이 위로 올라가는 모습 |
| 퀵 정렬 | 피벗 기준으로 좌·우 분할 후 재귀 정렬 | 기준선을 놓고 키 큰 사람·작은 사람을 양쪽으로 나누는 것 |
| 병합 정렬 | 배열을 절반씩 분할한 뒤 병합 단계에서 순서를 맞춤 | 카드 두 묶음을 한 장씩 비교하며 합치는 것 |
| 힙 정렬 | 최대 힙을 구성한 뒤 루트를 반복 추출하여 정렬 | 우선순위 줄에서 1등부터 차례로 빠지는 것 |

> 요약: 비교 기반 정렬은 교환·분할·선택 방식으로 나뉘며, 각각 버블·퀵/병합·힙이 대표적임

## Ⅲ. 절차
```text
[입력 배열] --> 분할/비교 --> 교환/병합 --> 반복 --> [정렬된 배열]
```
- 1단계: 정렬 대상 배열과 기준(비교 함수)을 입력받음
- 2단계: 알고리즘별 전략에 따라 원소를 비교함
  - 퀵: 피벗 선택 후 파티션
  - 병합: 재귀적으로 절반 분할
  - 힙: 최대 힙 구성(`heapify`)
  - 버블: 인접 쌍 순차 비교
- 3단계: 비교 결과에 따라 교환 또는 병합을 수행함
- 4단계: 부분 결과를 합쳐 최종 정렬 배열을 생성함

> 요약: 입력 → 비교 → 교환/병합 → 합산의 4단계로 정렬이 완료됨

## Ⅳ. 문제점
- 최악 시간 복잡도 편차: 퀵 정렬은 피벗이 편향되면 O(N^2)로 퇴화함 — 이미 정렬된 데이터에 고정 피벗을 쓰면 분할이 불균형해짐
- 추가 메모리 사용: 병합 정렬은 O(N) 보조 배열이 필요함 — 메모리 제약 환경에서 사용이 제한됨
- 안정성 미보장: 퀵 정렬·힙 정렬은 동일 키 원소의 상대 순서를 보존하지 않음 — 다중 키 정렬 시 결과가 예측 불가함

> 요약: 피벗 편향, 보조 메모리, 안정성 미보장이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 랜덤 피벗 또는 3-중앙값(Median-of-Three) 기법으로 퀵 정렬 최악 복잡도 발생 확률을 낮춤
2. 중기: 제자리 병합(In-place Merge) 또는 팀소트(Timsort) 적용으로 보조 메모리를 줄이면서 안정성을 확보함
3. 장기: 인트로소트(Introsort) 등 하이브리드 정렬 도입으로 최악 O(N log N)을 보장하면서 안정성도 유지함

> 요약: 피벗 전략 개선 → 제자리 병합 → 하이브리드 정렬 순으로 문제를 해소함

## Ⅵ. 전망
- 발전 방향: 병렬 정렬(GPU 기반), 외부 정렬(디스크 기반)로 대규모 데이터 처리 확대
- 기술사적 판단: 데이터 특성(크기, 분포, 메모리 제약)에 따라 적합한 알고리즘을 선택하는 역량이 핵심임
- 기술사 제언: 단일 알고리즘 암기보다 복잡도·안정성·메모리 트레이드오프를 종합 판단하는 설계 역량을 갖출 필요
