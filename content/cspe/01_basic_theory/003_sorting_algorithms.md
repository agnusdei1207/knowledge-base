# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 정렬 알고리즘은 무질서한 데이터를 특정 기준(오름차순 등)으로 재배치하는 알고리즘 묶음으로, **시간 복잡도**·공간 제약·안정성 세 축으로 성능이 갈린다.
- **왜 필요한가**: 이진 탐색·중복 제거·랭킹·DB 인덱스처럼 후속 처리가 '정렬된 상태'를 전제로 하기 때문이다.
- **핵심 직관**: 책장 정리에 한 권씩 꽂기(삽입)·절반씩 나눠 합치기(병합)·기준 잡아 양옆으로 던지기(퀵)가 있듯, 데이터 특성과 제약에 맞는 방법을 골라야 한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

O(N²)↔O(N log N)의 성능 의미는 001·002가 이미 다뤘으므로(참조), 여기서는 정렬 고유의 판단 축과 알고리즘 용어를 세운다. 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 정렬 알고리즘 (상위 키워드) | 데이터를 기준값 순서로 재배치하는 절차 | 흩어진 카드를 숫자순으로 줄 세우기 |
| 안정 정렬 (Stable) | 같은 값의 원래 입력 순서가 정렬 후에도 유지됨 | 국어 90점 동점자 입력 순서 그대로 보존 |
| 불안정 정렬 (Unstable) | 같은 값의 원래 순서가 뒤바뀔 수 있음 | 동점자 앞뒤가 바뀔 수 있음 |
| 제자리 정렬 (In-place) | O(1)~O(log N) 추가 공간만으로 원배열 안에서 정렬 | 여분 책상 없이 책장 안에서만 자리 바꾸기 |
| 피벗 (Pivot) | 퀵 정렬에서 좌·우를 가르는 기준값 | "가운데 애 나와, 작으면 좌·크면 우로!" |
| 분할 정복 (Divide & Conquer) | 문제를 반씩 쪼개 풀고 합치는 설계 패러다임 | 큰 빨래를 나눠 각자 개고 합치기 |
| 최대 힙 (Max Heap) | 부모가 자식보다 큰 완전 이진 트리 | 루트에 항상 최댓값이 떠 있는 피라미드 |
| 하이브리드 정렬 | 여러 정렬을 조합해 약점을 상쇄한 실무 정렬 | TimSort(삽입+병합), IntroSort(퀵+힙) |

## 깊이 이해
- **배경·문제의식**: O(N²)인 단순 정렬(버블·선택·삽입)은 구현이 쉬우나 N이 만 단위만 돼도 (001 수치 참조: N=10⁴에서 10⁸회) 멈춘다. 대규모에는 O(N log N)의 고급 정렬(퀵·병합·힙)이 필수다.
- **작동 원리 (고급 정렬 3종)**:
  - **퀵 정렬**: 피벗 기준으로 작은 값 좌·큰 값 우로 분할 후 재귀. 평균 O(N log N)으로 가장 빠르나, 피벗이 매번 최대/최솟값이면 O(N²)로 추락한다(불안정·제자리).
  - **병합 정렬**: 배열을 1개 크기까지 반씩 쪼갠 뒤 합치며 정렬. 입력 상태와 무관하게 항상 O(N log N)·안정 정렬이나, 합칠 때 O(N) 임시 배열이 반드시 필요하다.
  - **힙 정렬**: 최대 힙을 구성해 루트(최댓값)를 뽑아 배열 끝으로 보냄. 항상 O(N log N)·제자리이나, 참조가 트리 전역으로 튀어 캐시 적중률이 낮아 퀵보다 체감이 느리다(불안정).
- **비유**: 퀵은 "기준 잡고 좌우로 던지기"(빠르지만 쏠리면 망함), 병합은 "반씩 나눠 정렬해 오면 합쳐 줌"(안전·공평하나 임시 대기실 필요), 힙은 "가장 큰 것부터 꺼내 쌓기".
- **구체 예시**: 퀵은 평균이 빨라 원시 타입 정렬(Java `Arrays.sort(int[])`)에, 병합 계열은 안정성이 필요한 객체 정렬(Java `Collections.sort`)에 쓰인다(실제로는 TimSort 채택).
- **흔한 오해·주의점**: "무조건 퀵이 최고"는 오해다. 메모리가 극히 부족하면 O(N) 공간을 쓰는 병합을 못 쓰고, 동점 순서 보존이 필수인 다중 키 객체 정렬엔 불안정한 퀵을 못 쓴다.

## 연결 개념
- **시간·공간 복잡도 (001)**: 정렬 비교의 세 축(시간·공간·안정성) 중 앞 두 축의 뿌리.
- **빅오 표기법 (002)**: 최선/평균/최악을 O·Ω로 구분하는 근거 표기.
- **완전 이진 트리·분할 정복**: 힙 정렬과 퀵·병합 정렬의 기반 구조·패러다임.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정렬은 데이터를 기준값 순서로 재배치하는 과정으로, 시간 복잡도·공간 제약(In-place)·안정성(Stable)에 따라 성능이 극명히 갈림.
> 2. **가치**: 분산 데이터(Hadoop)·DB 인덱스에서 검색·조인 성능을 결정하는 핵심 전처리임.
> 3. **판단 포인트**: 데이터 규모·메모리 한계·동점 순서 유지 필요를 종합해 최적 알고리즘 또는 하이브리드 정렬을 선택하는 것이 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 종류별 시간·공간 복잡도 비교 | 퀵·병합·힙의 최선/평균/최악 시간과 공간 제약 | 버블·선택 정렬에만 지면 낭비 |
| 특성 기반 실무 선택 기준 | Stable·In-place 여부에 따른 선택 기준 | 학술 원리만 적고 실무 기준 누락 |
| 하이브리드 정렬 인지 | TimSort·IntroSort 채택 현황 | 퀵 정렬이 무조건 최고라고 단정 |

> 요약: 각 정렬의 복잡도·안정성·공간 제약을 비교하고, 실무 선택 기준과 하이브리드 정렬까지 제시해야 함.

## Ⅰ. 개요 및 필요성
- 개요: 무순서 데이터를 오름·내림차순으로 재배치해 검색·처리 효율을 높이는 절차임
- 배경: (001·002 참조) N 증가 시 O(N²) 단순 정렬은 병목이므로 분할 정복 기반 O(N log N) 정렬이 필요해짐
- 필요성: DB 인덱싱·이진 탐색·분산 처리(MapReduce)에서 선결되어야 할 필수 전제임

## Ⅱ. 구조 및 구성요소
선형 구조도 (정렬 분류):

    정렬 대상 데이터
      / 내부 정렬(메모리 内) -> O(N²): 버블·선택·삽입
      /                     -> O(N log N): 퀵·병합·힙
      / 외부 정렬(디스크 内) -> K-way 병합 (초대용량)

| 분류 기준 | 특성 | 판단 포인트 |
|:---|:---|:---|
| 안정성 | Stable: 동점 원순서 유지 / Unstable: 보장 불가 | 다중 키 객체 정렬 시 Stable 필수 |
| 공간 제약 | In-place: O(1)~O(log N) / Out-place: O(N) | 메모리 부족 환경에서 In-place 필수 |
| 데이터 상태 | 정렬·역정렬 등 초기 상태로 수행 시간 변동 | 퀵의 최악 O(N²) 방어 로직 필요 |

> 요약: 정렬은 처리 위치(내·외부)·안정성·공간 제약으로 분류해 상황에 맞는 알고리즘을 매핑함.

## Ⅲ. 동작원리 및 흐름도 (고급 정렬 3종)
선형 흐름도:

    배열 입력 -> 퀵: 피벗 분할 후 재귀
             /  병합: O(N) 공간 분할 후 병합
             /  힙: 최대 힙 구성 후 루트 추출
             -> 정렬된 배열

1. 퀵 정렬: 피벗 기준 좌·우 분할(Partition) 후 재귀 호출 (분할 정복)
2. 병합 정렬: 1개 크기까지 절반으로 쪼갠 뒤 임시 배열로 순서대로 병합
3. 힙 정렬: 최대 힙 구성 후 루트(최댓값)를 꺼내 배열 끝부터 채움
4. 공통 효과: 비교 횟수를 전수 비교(N²)가 아닌 트리 높이(log N)에 비례시켜 O(N log N)로 단축

> 요약: 분할 정복(퀵·병합)이나 힙 구조를 이용해 전체 비교 횟수를 O(N log N)로 낮춤.

## Ⅳ. 특징
- 속도: 평균적으로 퀵이 캐시 지역성(Cache Locality)이 좋아 상수항이 작고 체감 속도가 가장 빠름
- 메모리: 병합은 안정적이나 O(N) 임시 배열이 필요해 대용량에서 메모리 병목 우려가 있음
- 균일성: 힙·병합은 입력 상태와 무관하게 항상 O(N log N)을 보장함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 퀵 정렬 | 병합 정렬 | 힙 정렬 |
|:---|:---|:---|:---|
| 평균 시간 | O(N log N) | O(N log N) | O(N log N) |
| 최악 시간 | O(N²) | O(N log N) | O(N log N) |
| 추가 공간 | O(log N), In-place | O(N), Out-place | O(1), In-place |
| 안정성 | Unstable | Stable | Unstable |

> 요약: 속도 우선이면 퀵, 최악 보장·안정성이 필요하면 병합, 메모리 최소·최악 보장이 필요하면 힙을 선택함.

**리스크·대응:**
- 퀵 최악 O(N²): 정렬·역정렬 데이터 유입으로 재귀 깊이 최대화 → 무작위 피벗·중앙값(Median of 3) 채택 (지표: 정렬 Max 지연율)
- 병합 O(N) 메모리 고갈: 대용량 임시 배열로 OOM → In-place Merge 또는 청크 단위 분할 정렬 (지표: 메모리 피크 사용률)

**점검 지표:**
- 성능: 100만 건 정렬 소요 시간(ms) — APM 기반 수행 속도 측정
- 품질: 다중 키 정렬 시 순서 깨짐 오류율 — Stable 보장 여부 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 표준 라이브러리 하이브리드 채택: Java/Python이 삽입+병합을 결합한 TimSort(O(N log N)·Stable)를 기본 정렬로 사용
2. DB 정렬 최적화: `ORDER BY`가 워크스페이스를 초과하면 디스크 File Sort가 발생하므로, 인덱스 선행 정렬로 회피
3. 최악 입력 방어: 퀵을 기본으로 하되 재귀 깊이가 임계치를 넘으면 힙으로 전환하는 IntroSort로 O(N²) 유발 공격 방어

**결론:**
- 기술사 판단: 단일 최고 알고리즘은 없으며, 속도·메모리·안정성 트레이드오프를 반영한 하이브리드(TimSort·IntroSort)가 조건부 정답임
- 향후 방향: 멀티코어 활용을 위해 Parallel Merge Sort 등 병렬 분할 처리로 정렬을 가속하는 방향으로 진화 중임
