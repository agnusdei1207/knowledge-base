## 미리 알고가기

- 안정 정렬(Stable Sort): 동일한 키 값을 가진 원소들의 입력 순서가 정렬 후에도 유지되는 성질임
- 제자리 정렬(In-place Sort): 입력 배열 외에 추가적인 대규모 보조 메모리를 할당하지 않는 성질임
- 피벗(Pivot): 퀵 정렬에서 기준값으로 삼아 데이터를 좌우로 분할하는 원소임
- 힙(Heap): 부모 노드의 키가 자식보다 크거나 작은 완전 이진 트리 기반의 자료구조임

## Ⅰ. 개요

- **정의/개념**: 정렬 알고리즘은 무작위 데이터를 특정 기준 순서로 재배열하여 탐색·병합·통계 등 후속 연산의 효율성을 극대화하는 알고리즘 군임
- **배경/필요성**: 데이터가 무질서하면 탐색이나 조인 연산의 시간복잡도가 급격히 증가하므로, 데이터의 규모와 가용 자원 상황에 맞춰 최적의 정렬 방식을 선택해 시스템의 응답 성능을 보장해야 함

## Ⅱ. 특징

- 평균 시간복잡도는 $O(n \log n)$으로 수렴하지만, 알고리즘별로 최악의 상황에서의 지연 시간 보장 여부와 필요한 메모리 공간 사용량이 서로 다름
- 동일한 키 값에 대해 기존의 선후 관계를 보존해야 하는 데이터 정합성 요구에 따라 안정 정렬과 불안정 정렬로 구분하여 적용함
- 데이터의 초기 정렬 상태(정렬됨, 역정렬됨 등)에 따라 알고리즘의 실제 수행 효율이 크게 달라질 수 있어 입력 특성 분석이 선행되어야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 (Quick) | 병합 정렬 (Merge) | 힙 정렬 (Heap) | 버블 정렬 (Bubble) |
|:---|:---|:---|:---|:---|
| **처리 방식** | 피벗 기준 분할 정복 | 반분할 후 순차 병합 | 힙 구성 후 루트 추출 | 인접 원소 간 지속 교환 |
| **평균 시간** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| **최악 시간** | $O(n^2)$ (편향 발생) | $O(n \log n)$ 보장 | $O(n \log n)$ 보장 | $O(n^2)$ |
| **안정성** | 불안정 ($Unstable$) | 안정 ($Stable$) | 불안정 ($Unstable$) | 안정 ($Stable$) |
| **보조 공간** | $O(\log n)$ (스택) | $O(n)$ (추가 배열) | $O(1)$ (제자리) | $O(1)$ (제자리) |

> 요약: 퀵 정렬은 평균 속도가 가장 우수하며, 병합 정렬은 안정성을 보장하고, 힙 정렬은 추가 메모리 없이 최악의 지연 시간을 제어함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 함수 | 두 원소의 대소 관계를 판별하는 정렬의 기본 논리이며, 오름차순/내림차순 및 다중 키 순서를 정의함 |
| 분할/선택 구조 | 피벗 선택(퀵), 중간 지점 분할(병합), 힙 빌드(힙) 등 정렬 범위를 논리적으로 나누는 체계임 |
| 데이터 교환/이동 | 비교 결과를 바탕으로 실제 메모리상의 원소 위치를 스왑($Swap$)하거나 임시 공간으로 복사 병합함 |
| 임시 저장소 | 병합 정렬의 보조 배열이나 퀵 정렬의 재귀 호출 스택처럼 정렬 과정을 유지하기 위한 보조 공간임 |

```text
[ 정렬 처리 구조 ]
+----------+      +-------------+      +----------+
| 무질서    | ---> | 비교 및 분할  | ---> | 순서 보장  |
| 데이터 집합|      | 위치 스왑/병합|      | 결과 집합  |
+----------+      +-------------+      +----------+
                         |
                 (안정성/공간복잡도 고려)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 분할/트리구성 | --> | 반복 비교/스왑 | --> | 부분 집합 병합 | --> | 정렬 완료    |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **분할/구성** — 입력 데이터를 반으로 나누거나(병합), 피벗을 설정하거나(퀵), 이진 트리 형태의 힙을 구성함
2. **비교/스왑** — 인접한 원소 또는 피벗과 비교하여 조건에 맞지 않는 경우 위치를 직접 교환함
3. **병합/추출** — 분할된 부분 배열을 임시 공간에서 하나로 합치거나(병합), 힙의 루트를 하나씩 추출하여 정렬함
4. **정렬 완료** — 모든 재귀 호출이나 루프가 종료되고 전체 원소가 설정된 기준에 따라 정렬되었는지 최종 확인함

## Ⅵ. 실무 적용 및 유의점

1. 다중 조건 정렬(예: 이름순 정렬 후 나이순 정렬)이 필요한 업무에서는 병합 정렬 같은 안정 정렬을 선택하여 이전 정렬 결과가 훼손되지 않도록 정합성을 유지하고 최종 순서 지표로 검증해야 함
2. 메모리 사용량이 극히 제한된 임베디드 환경이나 실시간 성능 보장이 중요한 시스템에서는 메모리 스파이크가 없고 최악 지연 시간이 $O(n \log n)$으로 일정한 힙 정렬을 활용하여 시스템 타임아웃과 자원 고갈을 방지해야 함

## Ⅶ. 결론

- 정렬 알고리즘은 단순히 속도뿐만 아니라 가용 메모리, 데이터의 기존 순서 보존 필요성, 최악의 시나리오를 고려하여 설계해야 하며, 실무에서는 각 알고리즘의 트레이드오프를 명확히 판단하여 적용해야 함
