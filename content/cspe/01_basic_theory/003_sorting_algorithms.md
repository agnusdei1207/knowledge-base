## 미리 알고가기

- 안정 정렬(Stable Sort): 동일한 키 값을 가진 원소들의 입력 순서가 정렬 후에도 유지되는 성질임
- 제자리 정렬(In-place Sort): 입력 배열 외에 추가적인 대규모 보조 메모리를 할당하지 않는 성질임
- 피벗(Pivot): 퀵 정렬에서 기준값으로 삼아 데이터를 좌우로 분할하는 원소임
- 힙(Heap): 부모 노드의 키가 자식보다 크거나 작은 완전 이진 트리 기반의 자료구조임

## Ⅰ. 개요

- **정의/개념**: 정렬 알고리즘은 원소를 키 기준 순서로 재배열해 탐색·병합·집계 같은 후속 연산을 더 단순하게 하거나 처리 비용을 줄이는 알고리즘 군임
- **배경/필요성**: 정렬되지 않은 데이터에서는 이진 탐색, 순차 병합, 중복 제거 같은 처리가 어려워질 수 있으므로 입력 규모와 안정성 요구와 보조 메모리 제약에 맞는 정렬 방식을 선택해야 함

## Ⅱ. 특징

- 비교 기반 정렬은 대체로 $O(n \log n)$ 수준을 목표로 하지만, 버블 정렬처럼 $O(n^2)$에 머무르거나 퀵 정렬처럼 입력 분포에 따라 최악 $O(n^2)$로 퇴화할 수 있음
- 동일한 키 값에 대해 기존의 선후 관계를 보존해야 하는 데이터 정합성 요구에 따라 안정 정렬과 불안정 정렬로 구분하여 적용함
- 데이터의 초기 정렬 상태(정렬됨, 역정렬됨 등)에 따라 알고리즘의 실제 수행 효율이 크게 달라질 수 있어 입력 특성 분석이 선행되어야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퀵 정렬 (Quick) | 병합 정렬 (Merge) | 힙 정렬 (Heap) | 버블 정렬 (Bubble) |
|:---|:---|:---|:---|:---|
| **처리 방식** | 피벗 기준 분할 정복 | 반분할 후 순차 병합 | 힙 구성 후 루트 추출 | 인접 원소 간 지속 교환 |
| **평균 시간** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ |
| **최악 시간** | $O(n^2)$ (편향 발생) | $O(n \log n)$ 보장 | $O(n \log n)$ 보장 | $O(n^2)$ |
| **안정성** | 불안정 ($Unstable$) | 안정 ($Stable$) | 불안정 ($Unstable$) | 안정 ($Stable$) |
| **보조 공간** | 평균 $O(\log n)$, 편향 분할 시 최악 $O(n)$ 재귀 스택 | $O(n)$ (추가 배열) | $O(1)$ (제자리) | $O(1)$ (제자리) |

> 요약: 퀵 정렬은 평균 수행 시간이 낮은 편이나 최악 퇴화 가능성이 있고, 병합 정렬은 안정성, 힙 정렬은 보조 공간과 최악 시간 상한 관리에 유리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 함수 | 두 원소의 대소 관계를 판별하는 정렬의 기본 논리이며, 오름차순/내림차순 및 다중 키 순서를 정의함 |
| 분할/선택 구조 | 피벗 선택(퀵), 중간 지점 분할(병합), 힙 빌드(힙) 등 정렬 범위를 논리적으로 나누는 체계임 |
| 데이터 교환/이동 | 비교 결과를 바탕으로 실제 메모리상의 원소 위치를 스왑($Swap$)하거나 임시 공간으로 복사 병합함 |
| 임시 저장소 | 병합 정렬의 보조 배열이나 퀵 정렬의 재귀 호출 스택처럼 정렬 과정을 유지하기 위한 보조 공간임 |

```text
[ 정렬 처리 구조 ]
+----------+      +-------------+      +----------+
| 입력 원소  | ---> | 비교 및 분할  | ---> | 키 기준 결과 |
| 데이터 집합|      | 위치 스왑/병합|      | 결과 집합  |
+----------+      +-------------+      +----------+
                         |
                 (안정성/공간복잡도 고려)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 기준/구조 설정 | --> | 비교/이동 반복 | --> | 구간 확정    | --> | 결과 산출    |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **기준 설정** — 피벗, 분할 지점, 힙 구조, 인접 비교 기준처럼 알고리즘별 정렬 기준을 정함
2. **비교/이동** — 비교 결과에 따라 원소를 교환하거나 보조 배열로 이동해 부분 순서를 확정함
3. **구간 확정** — 분할된 구간, 병합된 구간, 힙에서 추출된 위치처럼 더 이상 바뀌지 않는 범위를 늘림
4. **결과 산출** — 재귀 호출이나 반복문이 종료되면 전체 원소가 설정된 키 기준 순서로 배치됨

## Ⅵ. 실무 적용 및 유의점

1. 다중 키 정렬에서는 병합 정렬 같은 안정 정렬을 사용해 동일 키 그룹 안의 이전 키 순서가 유지되는지 확인함
2. 입력 크기가 제한된 임베디드 환경에서는 힙 정렬로 보조 메모리를 고정하고 최악 수행시간 상한과 최대 메모리 사용량으로 타임아웃 위험을 확인함

## Ⅶ. 결론

- 정렬 알고리즘은 입력 분포, 안정성 요구, 보조 공간, 최악 시간 상한을 기준으로 선택해야 하며 평균 처리에는 퀵, 안정성에는 병합, 공간 제약과 시간 상한 관리에는 힙을 우선 검토함
