## 미리 알고가기

- 안정 정렬: 같은 키를 가진 원소의 기존 순서를 보존하는 정렬임
- 제자리 정렬: 입력 배열 외의 보조 공간을 상수 수준으로 쓰는 정렬임
- 비교 정렬: 원소 간 비교 결과만으로 순서를 결정하며 일반적으로 하한이 `Omega(n log n)`임

## Ⅰ. 개요

- **정의**: 데이터를 기준 순서로 재배열하는 알고리즘 군임
- **배경/필요성**: 탐색, 병합, 중복 제거, 순위 산정은 정렬 결과에 의존하므로 데이터 특성과 운영 제약에 맞는 정렬 선택이 필요함
- **비유**: 정렬은 창고 물건을 번호순으로 배치해 이후 찾기와 집계를 빠르게 만드는 작업임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주요 정렬의 복잡도와 선택 기준 비교 | 퀵·병합·힙·버블, 안정성, 제자리성, 최악 시간 | 평균·최악 혼동, 안정성 누락 |

> 요약: 정렬 문제는 복잡도 암기가 아니라 데이터 특성에 맞는 알고리즘 선택 문제임.

## Ⅱ. 특징/비교

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 시간복잡도 | 평균 `O(n log n)`, 최악 `O(n^2)` | 항상 `O(n log n)` | 항상 `O(n log n)` | 평균·최악 `O(n^2)` |
| 공간·안정성 | 제자리 가능, 일반 구현 불안정 | `O(n)` 보조공간, 안정 가능 | `O(1)` 보조공간, 불안정 | 제자리 가능, 안정 가능 |
| 선택 기준 | 캐시 친화와 평균 성능 | 안정성·외부 정렬 | 공간 제한과 최악 보장 | 교육용·소규모 검증 |

> 요약: 정렬 선택은 평균 속도, 최악 보장, 안정성, 보조 공간을 함께 비교해야 함.

- 대규모 일반 배열은 퀵 정렬 계열, 안정성이 필요한 레코드 정렬은 병합 정렬 계열이 적합함
- DB·파일 시스템처럼 디스크 블록 단위 처리가 필요한 경우 B-Tree나 외부 병합 정렬과 연결해 판단해야 함
- 버블 정렬은 시험에서 비교 기준을 설명하기 위한 기준선으로 다루며 실무 기본 선택지는 아님

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력배열 | ---> | 비교/분할 | ---> | 재배열   |
+----------+      +----------+      +----------+
                         |
                         v
                   +----------+
                   | 안정/공간 |
                   +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 비교 기준 | 오름차순·내림차순·복합 키처럼 원소 순서를 결정하는 규칙임 | 줄 세우는 기준표 |
| 분할·병합 | 퀵 정렬의 파티션, 병합 정렬의 병합처럼 문제를 나누고 합치는 동작임 | 상자를 나눠 정리한 뒤 합침 |
| 보조 공간 | 임시 배열, 재귀 스택, 힙 구조처럼 정렬 중 필요한 추가 공간임 | 임시 작업대 |
| 안정성 | 같은 키의 상대 순서를 보존하는 성질임 | 같은 번호표의 줄 순서 유지 |

> 요약: 정렬은 비교 기준, 재배열 방식, 보조 공간, 안정성으로 구조가 결정됨.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 요구파악 | ---> | 알고리즘선택 | ---> | 정렬수행 | ---> | 검증     |
+----------+      +----------+      +----------+      +----------+
```

1. **요구 파악**: 데이터 크기, 정렬 키, 안정성 필요 여부, 메모리 한계를 확인함
2. **알고리즘 선택**: 평균 성능, 최악 보장, 보조 공간 기준으로 후보를 좁힘
3. **정렬 수행**: 분할·병합·힙 구성 등 알고리즘별 핵심 연산을 실행함
4. **검증**: 정렬 순서, 동일 키 순서, 경계 데이터, 메모리 피크를 확인함

> 요약: 정렬 절차는 요구조건을 먼저 고정한 뒤 알고리즘을 선택하고 결과 속성을 검증하는 흐름임.

## Ⅴ. 문제점

- **P1 입력 분포 민감성**: 퀵 정렬은 피벗 선택이 나쁘면 이미 정렬된 데이터에서 최악 `O(n^2)`가 발생할 수 있음
- **P2 안정성·공간 제약 충돌**: 안정 정렬이 필요하면 병합 정렬이 적합하지만 `O(n)` 보조 공간이 부담될 수 있음
- **P3 저장매체 부적합**: 메모리 내부 정렬을 대용량 파일에 그대로 적용하면 랜덤 I/O와 메모리 부족이 병목이 됨

> 요약: 정렬 문제는 평균 복잡도만 보면 입력 분포, 안정성, 저장매체 제약을 놓치기 쉬움.

## Ⅵ. 개선방안

1. **단기**: 데이터 크기, 정렬 키, 안정성, 메모리 한계를 체크리스트로 확인함
2. **중기**: 퀵 정렬 최악을 줄이기 위해 랜덤 피벗, median-of-three, introsort를 적용함
3. **장기**: 대용량 데이터는 외부 병합 정렬, 분산 정렬, DB 인덱스 전략과 함께 설계함

- **P1 대응**: 피벗 전략과 최악 보장 알고리즘을 조합함 (확인: 정렬·역정렬 입력 테스트)
- **P2 대응**: 안정성 필요 시 병합 정렬, 공간 제한 시 힙 정렬·제자리 안정 정렬 가능성을 검토함 (확인: 안정성 테스트)
- **P3 대응**: 파일·분산 환경은 블록 I/O와 파티션 기준으로 정렬 전략을 재설계함 (확인: I/O 횟수, spill 크기)

> 요약: 정렬 개선은 알고리즘 자체보다 데이터 분포와 운영 제약에 맞춘 선택 기준 수립이 핵심임.

## Ⅶ. 전망

- 정렬은 DB, 검색엔진, 데이터 레이크의 기본 연산으로 남으며 메모리 계층과 병렬 처리 비용까지 고려하는 방향으로 확장됨
- GPU·분산 환경에서는 비교 횟수보다 데이터 이동량과 파티션 균형이 성능 지표가 됨
- 기술사는 정렬 알고리즘 이름보다 안정성, 최악 보장, 저장매체 특성을 연결해 선택 근거를 제시해야 함
