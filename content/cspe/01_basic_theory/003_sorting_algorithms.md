## 미리 알고가기

- 안정 정렬: 같은 키를 가진 원소의 기존 순서를 정렬 후에도 유지하는 정렬 방식임
- 제자리 정렬: 입력 배열 외에 큰 보조 배열을 거의 쓰지 않고 원소 위치를 바꾸는 정렬 방식임
- 피벗: 퀵 정렬에서 원소를 왼쪽과 오른쪽으로 나누는 기준값임
- 힙: 부모와 자식 사이의 우선순위 관계를 유지하는 완전 이진 트리 기반 구조임

## Ⅰ. 개요

- **정의/개념**: 정렬은 원소를 키 기준 순서로 다시 배치해 탐색, 병합, 집계 같은 후속 처리를 가능하게 만드는 알고리즘 군이며, 대표 방식으로 퀵 정렬, 병합 정렬, 힙 정렬, 버블 정렬이 있음
- **배경/필요성**: 데이터 규모가 커질수록 무질서한 입력은 검색과 집계 비용을 키우므로, 입력 분포와 메모리 제약에 맞게 비교 횟수와 데이터 이동량을 통제할 정렬 방식이 필요함

## Ⅱ. 특징

- 정렬 알고리즘은 비교 횟수와 데이터 이동량이 함께 성능을 좌우하므로 같은 복잡도라도 실제 실행시간이 달라질 수 있음
- 추가 메모리를 거의 쓰지 않는 제자리 정렬과 보조 배열을 쓰는 정렬은 메모리 한계와 안정성에서 선택 기준이 갈림
- 같은 키의 기존 순서를 유지하는지 여부가 다중 키 정렬과 로그 병합 결과의 정합성에 직접 영향을 줌
- 입력이 이미 정렬돼 있거나 역순인지 같은 분포 특성이 최악 성능을 크게 바꾸므로 평균 성능만으로 선택하면 위험함

## Ⅲ. 종류 및 비교

- **퀵 정렬**: 피벗을 기준으로 작은 값과 큰 값을 나누며 분할 정복으로 정렬하므로 평균 성능이 좋지만 피벗 편향에 민감함
- **병합 정렬**: 배열을 반으로 나눈 뒤 정렬된 부분 배열을 다시 합치므로 안정 정렬이 가능하고 성능이 일정함
- **힙 정렬**: 힙에서 최댓값 또는 최솟값을 반복해서 꺼내는 방식이므로 최악 성능을 보장하면서도 제자리 정렬이 가능함
- **버블 정렬**: 인접한 두 원소를 반복 비교해 큰 값을 뒤로 보내는 방식이므로 원리는 단순하지만 입력이 조금만 커져도 비교와 교환이 급증함

| 판단 기준 | 퀵 정렬 | 병합 정렬 | 힙 정렬 | 버블 정렬 |
|:---|:---|:---|:---|:---|
| 평균 시간복잡도 | 평균적으로 $O(n \log n)$이며 메모리 내 범용 정렬에 자주 쓰임 | 평균적으로 $O(n \log n)$이며 입력 분포와 무관하게 성능이 안정적임 | 평균적으로 $O(n \log n)$이며 힙 유지 비용이 함께 발생함 | 평균적으로 $O(n^2)$이므로 입력이 조금만 커져도 비교 횟수가 빠르게 늘어남 |
| 최악 시간복잡도 | 피벗이 한쪽으로 치우치면 $O(n^2)$까지 악화될 수 있음 | 항상 $O(n \log n)$을 유지하므로 최악 성능 예측이 쉬움 | 항상 $O(n \log n)$을 유지하므로 상한 관리가 쉬움 | 항상 $O(n^2)$이므로 실무 대용량 데이터에는 부적합함 |
| 추가 메모리 | 재귀 스택 정도만 주로 써 추가 메모리가 비교적 적음 | 병합용 임시 배열이 필요해 추가 메모리 부담이 큼 | 제자리 정렬이 가능해 추가 메모리가 비교적 적음 | 제자리 교환만 반복하므로 추가 메모리는 적음 |
| 동일 키 순서 보존 | 기본 구현만으로는 같은 키의 기존 순서를 보장하지 않음 | 같은 키의 기존 순서를 유지하므로 안정 정렬이 가능함 | 기본 구현만으로는 같은 키의 기존 순서를 보장하지 않음 | 인접 교환 방식이어서 같은 키의 기존 순서를 유지함 |
| 적합한 상황 | 평균 성능이 중요하고 메모리 내에서 범용 정렬을 수행할 때 적합함 | 순서 보존이 필요하거나 외부 저장장치와 함께 대용량 정렬을 해야 할 때 적합함 | 메모리 제약이 크고 최악 성능 상한을 관리해야 할 때 적합함 | 교육용 예제나 아주 작은 입력에서 동작 원리를 설명할 때만 적합함 |

> 요약: 퀵은 평균 성능, 병합은 안정성과 일관성, 힙은 메모리 제약과 최악 보장, 버블은 단순성에 강점이 있으므로 요구 조건이 다르면 선택도 달라짐

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비교 기준 키 | 숫자, 문자열, 시간처럼 정렬 순서를 정하는 기준이므로 비교 함수가 이 키와 맞아야 결과가 일관됨 |
| 분할 또는 우선순위 구조 | 퀵은 피벗 분할을 쓰고 병합은 분할 후 합치며 힙은 우선순위 구조를 유지하므로 이 구조가 비교 횟수와 메모리 접근 패턴을 좌우함 |
| 데이터 이동 방식 | 교환, 복사, 병합처럼 원소를 옮기는 방식이 다르므로 실제 실행시간과 쓰기 비용도 함께 달라짐 |
| 보조 메모리 | 임시 배열, 재귀 스택, 힙 유지 공간이 얼마나 필요한지가 적용 가능한 환경을 가름함 |

> 요약: 정렬 방식의 차이는 무엇을 기준으로 비교하고, 어떻게 분할하며, 원소를 어떻게 옮기고, 추가 메모리를 얼마나 쓰는지에서 갈림

```text
+------------+     +------------------+     +------------------+     +---------------+
| Input data | --> | Partition / Heap | --> | Compare and move | --> | Sorted output |
+------------+     +------------------+     +------------------+     +---------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 기준설정 | --> | 구조구성 | --> | 반복정렬 | --> | 결과확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **정렬 기준 설정**: 비교 키와 오름차순 또는 내림차순 기준을 정함
2. **구조 구성**: 퀵은 피벗으로 나누고 병합은 절반으로 나누며 힙은 우선순위 구조를 만들고 버블은 인접 비교 순서를 잡음
3. **비교와 이동 반복**: 부분 배열 정렬, 병합, 힙 재구성, 인접 교환을 반복함
4. **결과 확정**: 전체 구간이 기준 순서를 만족하는지 확인하고 정렬을 끝냄

## Ⅵ. 실무 적용 및 유의점

1. 로그 배치 정렬에서는 같은 시각 레코드의 기존 순서까지 유지해야 하므로 안정 정렬을 쓰고 배치 시간과 정렬 정확도로 확인함
2. 메모리가 작은 장비에서는 병합 정렬처럼 큰 보조 배열이 부담이 되므로 힙 정렬 같은 제자리 정렬을 쓰고 피크 메모리와 처리 지연으로 확인함

## Ⅶ. 결론

정렬 알고리즘은 평균 속도만 볼 일이 아니라 입력 분포, 추가 메모리, 동일 키 순서 보존 요구를 함께 따져 선택해야 함.
