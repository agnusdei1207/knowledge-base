## Ⅰ. 개요
- **정의**: 소스 코드 문자열을 토큰 단위로 분할하는 컴파일러 첫 단계
- **배경/필요성**: 문자 스트림 그대로는 문법 규칙 적용이 불가하므로, 의미 있는 최소 단위로 분리가 선행되어야 함
- **비유**: 문장을 띄어쓰기·구두점 기준으로 단어 카드로 나누는 작업과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 컴파일러 전단부 이해도 확인 | 정규 표현식 → NFA → DFA 변환 과정 | 토큰·패턴·렉심 3개념 구분 누락 시 감점 |

> 요약: 소스 문자열을 토큰으로 분리하여 구문 분석기에 전달하는 단계임

## Ⅱ. 구성요소
```text
  Source Code
       |
       v
  +----------+     +----------+     +----------+
  | Scanner  |---->| Token    |---->| Symbol   |
  | (Lexer)  |     | Stream   |     | Table    |
  +----------+     +----------+     +----------+
       |
       v
  Error Handler
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Scanner(Lexer) | 입력 문자열을 정규 표현식 기반으로 토큰 단위 분리하는 모듈 | 문장에서 단어를 잘라내는 가위 |
| Token Stream | 식별자·키워드·연산자 등 분류된 토큰의 순서열 | 단어 카드가 순서대로 놓인 줄 |
| Symbol Table | 식별자 이름·타입·스코프 정보를 저장하는 자료구조 | 단어장에 뜻과 품사를 기록하는 표 |
| Pattern/Regex | 각 토큰 종류를 인식하기 위한 정규 표현식 정의 | 단어 분류 기준표 |
| Error Handler | 인식 불가 문자 발견 시 오류 보고 및 복구 수행 | 오탈자 검출기 |

> 요약: 스캐너가 정규 표현식으로 문자열을 토큰화하고, 심볼 테이블에 식별자 정보를 등록함

## Ⅲ. 절차
```text
  정규표현식정의    NFA구성          DFA변환          토큰출력
  (패턴 명세)     (Thompson)      (Subset Const.)  (최장일치)
       |              |              |              |
       +---변환------->+---결정화----->+---스캔------->+
    토큰 규칙       비결정 오토마타  결정 오토마타    토큰 스트림
```
- 1단계: 토큰 종류별 정규 표현식을 정의하여 패턴 명세를 작성함
- 2단계: 각 정규 표현식을 Thompson 구성법으로 NFA로 변환함
- 3단계: 부분집합 구성법(Subset Construction)으로 NFA를 DFA로 변환함
- 4단계: DFA를 이용해 입력 문자열에 최장 일치(Longest Match) 규칙을 적용하여 토큰을 출력함

> 요약: 정규 표현식 → NFA → DFA → 최장 일치 스캔 순서로 토큰을 생성함

## Ⅳ. 문제점
- DFA 상태 폭발: 정규 표현식이 복잡할수록 DFA 상태 수가 지수적으로 증가하여 메모리 소비가 과대해짐
- 최장 일치 모호성: 여러 패턴이 동일 길이로 매칭될 때 우선순위 규칙이 없으면 토큰 분류 오류 발생함
- 에러 복구 한계: 인식 불가 문자 발견 시 단순 스킵 방식은 후속 토큰까지 연쇄 오분류를 유발함

> 요약: 상태 폭발·매칭 모호성·에러 복구 한계가 어휘 분석의 주요 문제임

## Ⅴ. 개선방안
1. 단기: DFA 최소화 알고리즘(Hopcroft) 적용으로 등가 상태 병합하여 상태 수 축소
2. 중기: 토큰 우선순위 규칙(키워드 우선, 선언 순서 우선)을 명시적으로 정의하여 모호성 제거
3. 장기: Panic-mode 대신 문맥 기반 에러 복구 전략을 도입하여 연쇄 오분류 차단

> 요약: DFA 최소화·우선순위 명시·문맥 기반 복구로 어휘 분석 품질을 향상함

## Ⅵ. 전망
- 발전 방향: IDE 실시간 증분 렉싱(Incremental Lexing)으로 편집 시 변경 부분만 재토큰화하는 방식 확산
- 기술사적 판단: 어휘 분석은 컴파일러뿐 아니라 정적 분석·코드 검색·구문 하이라이팅 등 광범위한 도구의 기반 기술임
- 기술사 제언: 정규 표현식과 유한 오토마타 이론의 정확한 이해가 컴파일러 전단부 설계의 출발점임
