## 미리 알고가기

- 알파벳 $\Sigma$: 문자열을 구성하는 단말 기호 집합임
- 문법 $G=(V,\Sigma,P,S)$: 비단말, 단말, 생성 규칙, 시작 기호로 언어를 정의함
- DFA/NFA: 정규 언어를 인식하는 유한 상태 기계임

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 유한 오토마타로 인식 가능하고 정규 표현식으로 기술 가능한 형식 언어이며, 정규 문법은 그 언어를 생성하는 Type-3 문법임
- **배경/필요성**: 어휘 분석, 패턴 매칭, 입력 검증처럼 상태 수가 유한한 문제를 빠르게 처리하려면 단순하면서 닫힘 성질이 좋은 언어 모델이 필요함

## Ⅱ. 특징

- 메모리 스택 없이 현재 상태만으로 인식 가능해 처리 구조가 단순함
- 합집합, 연결, 반복에 대해 닫혀 있어 패턴 조합과 자동화가 쉬움
- DFA로 변환하면 입력 길이 $n$에 대해 $O(n)$으로 안정적으로 처리 가능함
- 중첩 괄호나 $a^n b^n$ 같은 장거리 의존성은 표현하지 못함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 언어 | 문맥 자유 언어 |
|:---|:---|:---|
| 인식 모델 | DFA, NFA | PDA |
| 기억 구조 | 유한 상태 | 상태 + 스택 |
| 표현 가능한 구조 | 반복, 선택, 단순 패턴 | 중첩, 재귀 구조 |
| 대표 적용 | 정규식, Lexer | Parser, 구문 분석 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 집합 $Q$ | 입력 처리 중 현재 위치를 표현하고 인식 능력의 범위를 결정함 |
| 입력 알파벳 $\Sigma$ | 허용 문자와 기호 집합이며 토큰 정의의 기준임 |
| 전이 함수 $\delta$ | 상태와 입력을 다음 상태로 연결하고 실제 처리 로직임 |
| 종료 상태 $F$ | 수용 여부를 판정하고 패턴 매칭 성공 조건임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 패턴정의 | --> | 오토마타 구성 | --> | 입력스캔 | --> | 수용판정 |
+----------+     +----------+     +----------+     +----------+
```

1. **패턴정의**: 정규식 또는 정규 문법으로 허용 문자열을 정의함
2. **오토마타 구성**: NFA 또는 DFA로 상태 전이 구조를 만듦
3. **입력스캔**: 문자를 한 글자씩 읽으며 상태를 전이함
4. **수용판정**: 종료 시 수용 상태면 언어에 속한다고 판단함

## Ⅵ. 문제점 및 해결 방안

1. **중첩 구조를 표현하지 못함**: 유한 상태만으로는 깊이 의존 관계를 저장할 수 없음
   - **해결 방안**: 괄호 중첩, 블록 구조는 CFG와 PDA로 상향 설계하고 중첩 문장 인식률로 검증함
2. **복잡한 정규식은 성능과 가독성이 저하됨**: 백트래킹 엔진은 패턴에 따라 급격히 느려질 수 있음
   - **해결 방안**: DFA 기반 처리, 패턴 분해, 타임아웃 정책을 적용하고 매칭 지연시간로 검증함
3. **규칙 관리가 분산되면 검증 누락이 발생함**: 서비스별 정규식 편차가 커질 수 있음
   - **해결 방안**: 공통 패턴 라이브러리와 테스트 케이스를 표준화하고 규칙 재사용률로 검증함

## Ⅶ. 적용 사례

- 컴파일러 어휘 분석기: 예약어와 식별자 패턴을 DFA로 처리함, 확인 지표는 토큰 인식 속도와 정확도임
- 웹 입력 검증: 이메일, URL, 로그 포맷을 정규식으로 검사함, 확인 지표는 오탐률과 응답시간임
- 보안 탐지 룰: 단순 공격 시그니처를 패턴으로 필터링함, 확인 지표는 탐지율과 ReDoS 발생 여부임

## Ⅷ. 결론

정규 언어는 유한 상태 기반 고속 처리에 최적이지만 중첩 구조에는 한계가 있으므로, 패턴 검증은 정규 언어로 처리하고 구문 해석은 상위 문법으로 분리하는 것이 핵심 판단임.
