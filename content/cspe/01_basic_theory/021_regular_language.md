## 미리 알고가기

- 촘스키 계층(Chomsky Hierarchy): 언어의 생성 복잡도에 따라 정규, 문맥 자유, 문맥 의존, 무제약 언어의 4단계로 분류한 체계임
- Type-3 문법: 촘스키 계층 중 가장 단순한 등급으로, 유한 오토마타로 표현 가능한 정규 문법이 여기에 해당함
- 알파벳($\Sigma$): 문자열을 구성하는 기본 기호들의 유한 집합임 (예: 이진 언어의 경우 $\{0, 1\}$)
- 클리니 스타($*$): 특정 기호나 문자열의 0회 이상 반복을 의미하는 연산자임

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 유한한 상태 정보만을 이용하는 유한 오토마타가 인식할 수 있는 문자열의 집합이며, 정규 문법은 이 문자열들을 생성해내는 $A \rightarrow aB$ 또는 $A \rightarrow a$ 형태의 생성 규칙(Type-3)임
- **배경/필요성**: 소스코드의 키워드 추출, 이메일 형식 검증, 로그 패턴 매칭 등 복잡한 기억 장치(스택 등) 없이 단순한 상태 전이만으로도 처리가 가능한 효율적인 텍스트 분석 모델이 필요함

## Ⅱ. 특징

- 현재 상태 정보만으로 다음 동작을 결정하므로 별도의 메모리(스택)가 필요 없으며, 연산 결과가 항상 정규 언어 집합 내에 포함되는 닫힘 성질($Union$, $Concat$, $Star$ 등)을 가짐
- 입력 문자열의 길이($n$)에 대해 $O(n)$의 선형 시간복잡도로 패턴 매칭이 가능하여, 실시간 데이터 스트림이나 대용량 로그 분석에서 예측 가능한 처리 성능을 보장함
- $a^n b^n$과 같이 '개수'를 기억하여 서로 대칭을 이루어야 하는 중첩 구조는 표현할 수 없는 명확한 한계를 지니며, 오직 반복($Repetition$)과 선택($Selection$)의 조합으로만 구성됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 언어·문법 (Regular) | 문맥 자유 언어·문법 (Context-Free) |
|:---|:---|:---|
| **촘스키 위계** | Type-3 (가장 단순) | Type-2 |
| **인식 모델** | 유한 오토마타 (DFA/NFA) | 푸시다운 오토마타 (PDA) |
| **기억 장치** | 유한 상태 ($Finite$ $State$) | 상태 + 스택 ($Stack$) |
| **표현 한계** | 중첩 구조 표현 불가 | 재귀적 중첩 구조($a^n b^n$) 가능 |
| **주요 활용** | 정규 표현식, 어휘 분석기($Lexer$) | 구문 분석기($Parser$), $XML$, $HTML$ |

> 요약: 단순한 패턴 매칭은 정규 언어를, 복잡한 중첩 구조 파싱은 문맥 자유 언어를 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단말 기호 ($\Sigma$) | 문자열의 최종 형태를 구성하는 실제 데이터 기호들의 집합임 |
| 비단말 기호 ($V$) | 문자열 생성 과정에서 다른 기호로 대체되는 중간 매개체(상태)임 |
| 생성 규칙 ($P$) | $A \rightarrow aB$ 또는 $A \rightarrow a$와 같이 규칙 오른쪽에 최대 하나의 비단말 기호만 허용함 |
| 정규 표현식 ($RE$) | 문법을 간결하게 기술하기 위한 기호 체계로 $|$(선택), $\cdot$(연결), $*(반복)를 사용함 |

```text
[ 정규 문법 생성 규칙 예시 ]
S -> aA | bB  (S에서 a를 읽고 A로 가거나 b를 읽고 B로 감)
A -> aA | ε   (A에서 a를 반복하거나 종료)
B -> bB | ε   (B에서 b를 반복하거나 종료)
=> 정규식: a* | b*
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 입력 데이터  | --> | 상태 전이 실행 | --> | 리프 상태 도달 | --> | 수용/거부 판정|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **입력 수신** — 판정할 문자열을 한 글자씩 순차적으로 읽어 들이며 초기 상태($S$)에서 시작함
2. **상태 전이** — 현재 상태와 입력된 단말 기호($a, b$ 등)를 조합하여 생성 규칙에 정의된 다음 비단말 기호(상태)로 이동함
3. **반복 처리** — 문자열의 모든 기호를 소비할 때까지 추가적인 메모리 참조 없이 오직 현재 상태값만 갱신하며 전이를 지속함
4. **결과 확정** — 모든 입력이 끝난 후 도달한 최종 상태가 수용 상태($Final$ $State$)이면 유효한 언어로 판정하고, 아니면 거부함

## Ⅵ. 실무 적용 및 유의점

1. 어휘 분석기($Lexer$) 설계 시 정규 문법을 사용하면 토큰 추출 속도는 빠르지만, $HTML$ 태그의 중첩이나 괄호 짝 맞추기 로직을 정규식 하나로 해결하려 들면 오류가 발생하므로 반드시 스택 기반의 파서와 역할을 분담해야 함
2. 비결정적 규칙($NFA$)을 결정적 규칙($DFA$)으로 변환하는 과정에서 상태의 개수가 지수적으로 폭증하여 메모리 부족($OOM$)이 발생할 수 있으므로, 규칙을 최소화($State$ $Minimization$)하고 복잡한 정규식의 남용을 경계해야 함

## Ⅶ. 결론

- 정규 언어·문법은 텍스트 처리의 가장 기초적이고 효율적인 논리 체계이며, 설계자는 모델의 표현 한계와 연산 비용을 명확히 이해하여 시스템의 데이터 정합성과 처리 성능을 동시에 확보해야 함
