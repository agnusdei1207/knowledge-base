## 미리 알고가기

- 형식 언어: 알파벳으로 만들 수 있는 문자열 중 규칙을 만족하는 문자열 집합임
- 정규 표현식: 선택, 연결, 반복 연산으로 문자열 패턴을 기술하는 표기법임
- DFA/NFA: 유한한 상태 전이로 문자열 수용 여부를 판단하는 오토마타임
- 정규 문법: `A -> aB`, `A -> a`, `A -> epsilon`처럼 우변 구조가 제한된 Type-3 문법임
- 펌핑 보조정리: 어떤 언어가 정규 언어가 아님을 보일 때 쓰는 증명 도구임

## Ⅰ. 개요

- **정의**: 정규 언어는 문자열 집합을 유한 상태 전이로 판정할 수 있는 형식 언어이며, 입력이 정해진 패턴을 만족하는지 빠르고 예측 가능하게 검사하기 위해 사용함.
- **배경/필요성**: 컴파일러 어휘 분석, 로그 필터링, 프로토콜 필드 검증은 중첩 기억보다 선형 시간 판정이 중요하므로 정규 표현식, 유한 오토마타, 정규 문법의 동치 관계를 이해해야 함.
- **비유**: 입력 문자가 들어올 때마다 정해진 문으로 이동하고 마지막에 허용된 방에 있으면 통과시키는 자동 출입 게이트와 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 언어의 표현과 인식 방법 설명 | 정규 표현식, DFA/NFA, 정규 문법의 동치성 | 오토마타와 문법 관계 누락 |
| 정규 언어의 한계 판단 | 유한 상태, 닫힘 성질, 펌핑 보조정리 | 문맥 자유 언어와 표현력 혼동 |

> 요약: 정규 언어는 중첩 기억 없이 현재 상태만으로 문자열 패턴을 판정하는 가장 제한적이지만 구현 효율이 높은 언어 클래스임.

## Ⅱ. 특징/비교

| 판단 기준 | 정규 언어 | 문맥 자유 언어 |
|:---|:---|:---|
| 기억 구조 | 유한 상태만 유지해 이전 입력을 요약함 | 스택으로 중첩 구조와 재귀를 저장함 |
| 표현 대상 | 반복, 선택, 연결처럼 평면적인 패턴에 적합함 | 괄호 짝, 블록 구조, 중첩 구문에 적합함 |
| 구현 방식 | DFA 전이표, NFA 시뮬레이션, 정규식 엔진으로 구현함 | 파서와 파스 트리 생성 절차가 필요함 |
| 선택 기준 | 속도, 단순 검증, 최악 시간 예측성이 중요할 때 선택함 | 구문 구조와 계층 의미를 보존해야 할 때 선택함 |

- **적용 기준**: 입력이 필드 형식, 토큰, 단순 반복 패턴이면 정규 언어로 먼저 모델링함.
- **회피 기준**: 괄호 수 일치, XML 중첩, 프로그램 블록처럼 무한한 기억이 필요하면 CFG로 넘김.
- **검증 기준**: 정규 표현식과 DFA가 같은 언어를 수용하는지 테스트 케이스와 경계 문자열로 확인함.

> 요약: 정규 언어는 표현력을 제한하는 대신 빠른 판정과 단순 구현을 얻는 선택이며, 중첩 구조가 보이면 다른 언어 클래스로 분리해야 함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Pattern    | ---> | Automata   | ---> | Decision   |
| Expression |      | DFA / NFA  |      | Accept/No  |
+------------+      +------------+      +------------+
       |                   |
       v                   v
+------------+      +------------+
| Regular    |      | Closure /  |
| Grammar    |      | Pumping    |
+------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정규 표현식 | 허용할 문자열 집합을 패턴 연산자로 선언적으로 기술함 | 검색 조건식 |
| 유한 오토마타 | 상태 집합, 입력 알파벳, 전이 함수, 시작 상태, 수용 상태로 문자열을 판정함 | 자동 검사기 |
| 정규 문법 | 제한된 생성 규칙으로 정규 언어에 속하는 문자열을 생성함 | 조립 설명서 |
| 닫힘 성질 | 합집합, 연결, 반복, 여집합 등 연산 후에도 정규성이 유지되는지 판단함 | 품질 보증 기준 |
| 펌핑 보조정리 | 긴 문자열을 세 부분으로 나누어 반복 가능성을 보이며 비정규성을 증명함 | 한계 검사 도구 |

> 요약: 정규 언어는 표현식, 오토마타, 문법이 같은 언어를 서로 다른 관점에서 나타내고, 성질 검증으로 적용 가능 범위를 확정함.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Pattern    | ---> | NFA        | ---> | DFA        | ---> | Validate   |
| Define     |      | Build      |      | Optimize   |      | Language   |
+------------+      +------------+      +------------+      +------------+
```

1. **패턴 정의**: 허용할 문자열 규칙을 정규 표현식 또는 정규 문법으로 기술하고 알파벳 범위를 정함.
2. **오토마타 구성**: Thompson 구성 등으로 NFA를 만들고 시작 상태와 수용 상태를 지정함.
3. **결정화·최소화**: 부분집합 구성법으로 DFA를 만들고 동치 상태를 병합해 전이표를 줄임.
4. **판정·검증**: 정상 문자열, 오류 문자열, 경계 문자열을 입력해 수용 언어가 요구사항과 일치하는지 확인함.

> 요약: 정규 언어 적용은 패턴을 오토마타로 바꾸고 최소화한 뒤, 요구 문자열 집합과 실제 수용 결과를 대조하는 과정임.

## Ⅴ. 문제점

- **P1 상태 폭발**: NFA를 DFA로 변환할 때 상태 조합이 지수적으로 늘어나 전이표 메모리와 생성 시간이 커질 수 있음.
- **P2 표현력 한계**: 유한 상태만 사용하므로 `a^n b^n` 같은 개수 일치나 임의 깊이의 중첩 구조를 표현할 수 없음.
- **P3 실용 정규식 혼동**: 역참조와 일부 탐색 기능을 쓰는 엔진은 이론적 정규 언어를 넘어 최악 입력에서 매칭 지연을 유발할 수 있음.

> 요약: 정규 언어는 빠른 판정이 강점이지만 상태 수, 표현 범위, 엔진 확장 기능을 통제하지 않으면 성능과 정확성이 깨짐.

## Ⅵ. 개선방안

- **P1 대응**: Lazy DFA, NFA 시뮬레이션, 상태 최소화를 적용해 필요한 상태만 만들고 전이표 크기를 감시함. (확인: 상태 수, p99 매칭 시간)
- **P2 대응**: 중첩 문법은 CFG/PDA 또는 전용 파서로 분리하고 정규 언어는 어휘·필드 검증에 한정함. (확인: 토큰 검증과 구문 분석 경계)
- **P3 대응**: 선형 시간 정규식 엔진, 패턴 타임아웃, 역참조 제한을 적용해 ReDoS 위험을 차단함. (확인: 최악 입력 매칭 시간)

> 요약: 정규 언어는 적용 범위를 단순 패턴 판정으로 제한하고 구현 엔진의 시간 특성을 검증할 때 안정적으로 활용할 수 있음.

## Ⅶ. 전망

- **향후 발전 방향**: 로그 분석, 네트워크 필터링, WAF, 컴파일러 전처리에서 정규 언어 기반 고속 매칭은 계속 사용될 전망임.
- **기술사적 판단**: 표현력보다 예측 가능한 성능과 단순 운영이 중요한 입력 검증 영역에 우선 적용해야 함.
- **기술사 제언**: 답안에서는 DFA/NFA/정규 표현식의 동치성과 CFG 대비 한계를 함께 제시해 선택 기준을 분명히 해야 함.

답안 정리:
- **핵심 키워드**: 유한 상태, 정규 표현식, DFA/NFA, 정규 문법, 펌핑 보조정리임.
- **연계 키워드**: 오토마타 이론, 문맥 자유 문법, 컴파일러 어휘 분석으로 연결함.
- **검증 관점**: 주어진 언어가 중첩 기억 없이 판정 가능한지 먼저 확인함.
