# 021. 정규 언어·문법 (Regular Language and Grammar) [출제: -]

## 미리 알고가기

- **형식 언어 (Formal Language)**: 특정한 규칙(문법)에 의해 생성된 문자열들의 집합임
- **생성 규칙 (Production Rule)**: 언어 내의 유효한 문자열을 만들기 위한 치환 규칙 ($A \rightarrow \alpha$)
- **촘스키 계층 (Chomsky Hierarchy)**: 언어의 생성 규칙에 제약을 두어 $4$단계(Type $0 \sim 3$)로 분류한 체계이며, 정규 언어는 이 중 가장 제한적인 Type $3$에 해당함

## Ⅰ. 개요

- **정의/개념**: 정규 언어(Regular Language)는 유한 오토마타로 인식 가능하거나 정규 표현식으로 나타낼 수 있는 언어이며, 정규 문법(Regular Grammar)은 이를 생성하기 위한 가장 단순한 형태의 문법 체계임
- **배경/필요성**: 프로그래밍 언어의 낱말(Token) 구조를 정의하고 식별하는 데 최적화되어 있음. 컴파일러의 첫 번째 단계인 어휘 분석(Lexical Analysis)의 이론적 기반이며, 텍스트 검색 및 유효성 검사 도구의 핵심 원리임

## Ⅱ. 특징 및 비교

정규 언어는 촘스키 계층의 최하단에 위치하며, 계산 모델 중 가장 단순한 유한 오토마타와 $1:1$ 대응됨.

| 계층 (Type) | 언어 명칭 | 인식 모델 | 문법 제약 (Production) | 예시 |
|:---|:---|:---|:---|:---|
| **Type $3$** | **정규 언어** | **유한 오토마타 (FA)** | $A \rightarrow aB$ 또는 $A \rightarrow a$ (한쪽 방향) | 식별자, 숫자, 이메일 형식 |
| **Type $2$** | 문맥 자유 언어 | 푸시다운 오토마타 (PDA) | $A \rightarrow \gamma$ (좌변이 비단말 기호 하나) | 괄호 짝, 프로토콜 구조 |
| **Type $1$** | 문맥 의존 언어 | 선형 유한 오토마타 (LBA) | $\alpha A \beta \rightarrow \alpha \gamma \beta$ | 자연어 처리의 일부 |
| **Type $0$** | 무제약 언어 | 튜링 머신 (TM) | 제약 없음 | 모든 계산 가능한 문제 |

> 요약: 정규 언어는 '상태'만 기억할 수 있고 '메모리(스택)'가 없어 중첩된 구조(예: $a^n b^n$)는 표현하지 못함.

## Ⅲ. 구성요소/구조

정규 문법은 비단말 기호(Variables), 단말 기호(Terminals), 시작 기호(Start), 생성 규칙(Rules)의 $4$요소($G = (V, \Sigma, R, S)$)로 정의됨.

- **정규 문법의 유형**:
  - **우측 정규 문법 (Right Linear)**: 생성 규칙이 $A \rightarrow aB$ 또는 $A \rightarrow a$ 형태임 (비단말 기호가 우측 끝에 위치)
  - **좌측 정규 문법 (Left Linear)**: 생성 규칙이 $A \rightarrow Ba$ 또는 $A \rightarrow a$ 형태임 (비단말 기호가 좌측 끝에 위치)
  - **주의**: 한 문법 내에서 우측과 좌측 규칙을 혼용하면 더 이상 정규 문법이 아님

- **등가성 구조 (Kleene's Theorem)**:

```text
[Regular Expression] <---> [Regular Grammar] <---> [Finite Automata]
      (표현식)                    (생성 규칙)                 (인식 기계)
```

1. **상호 변환**: 정규 표현식으로 기술된 패턴은 항상 유한 오토마타로 변환되어 실행될 수 있음
2. **동작 원리**: 정규 문법의 비단말 기호($V$)는 오토마타의 '상태'와 매핑되며, 단말 기호($\Sigma$)는 '입력 값'과 매핑됨

## Ⅳ. 문제점 및 개선방안

1. **표현력의 한계 (Pumping Lemma)**: 괄호의 중첩이나 동일한 개수를 세어야 하는 구조($a^n b^n$)를 정규 언어로는 판별할 수 없음
   - **개선방안**: 정규 언어 여부를 판별하기 위해 **펌핑 레마(Pumping Lemma)**를 적용하여 모순을 증명하고, 필요한 경우 상위 계층인 문맥 자유 문법(CFG)을 도입함 (확인: 언어의 재귀적 특성 분석)

2. **정규 표현식 오남용**: 복잡한 HTML 파싱이나 중첩 구조를 정규 표현식만으로 해결하려다 '지옥의 패턴(Regex Hell)'에 빠짐
   - **개선방안**: 어휘 분석(Regex)과 구문 분석(Parser)을 명확히 분리하여 설계함. 단순 토큰화는 정규식으로, 구조 해석은 파서로 처리함 (확인: 파이프라인 설계의 적절성)

3. **성능 저하 (ReDoS)**: NFA 기반 매칭 엔진에서 지수 시간의 탐색이 발생하는 악의적 패턴이 서비스 거부를 유발함
   - **개선방안**: 정규 표현식을 DFA로 컴파일하여 선형 시간($O(n)$) 보장 매칭을 수행하거나, 중첩된 한정사(nested quantifiers) 사용을 제한함 (확인: 매칭 엔진의 최악 시나리오 복잡도)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 프로그래밍 언어 Lexer | `if`, `while`, `[a-zA-Z_][a-zA-Z0-9_]*` 등의 토큰 형식을 정규 문법으로 정의하여 코드 스캔 | 토큰 인식 오류율, 스캔 속도 |
| 네트워크 패킷 필터링 | IP 주소, 포트 번호, 특정 프로토콜 헤더 패턴을 정규 표현식으로 검사하여 방화벽 적용 | 초당 처리 패킷 수(PPS), 차단 정확도 |
| 데이터 전처리 (ETL) | 로그 파일 내의 타임스탬프, 에러 코드 등 정형화된 텍스트 데이터를 정규식으로 추출 및 변환 | 데이터 추출 정밀도(Precision), 재현율(Recall) |
| 검색 엔진 인덱싱 | 웹 페이지 내의 키워드를 추출하거나 URL 패턴을 분류하여 크롤링 범위 설정 | 인덱싱 완료 시간, 크롤링 성공률 |

> 요약: 정형화된 문자열 패턴의 생성과 인식에 있어 가장 효율적이고 보편적인 도구임.

## Ⅵ. 결론

정규 언어와 문법은 형식 언어 이론의 시작점이자 실무적으로 가장 빈번히 사용되는 기술임. 기술사는 정규 언어가 가진 '유한 상태'라는 제약이 가져오는 명확한 한계를 이해하고, 이를 통해 $O(n)$의 성능 보장이라는 강력한 이점을 취할 수 있어야 함.

특히 최신 개발 환경에서는 정규 표현식의 유연함에 가려진 성능 병목과 보안 위협(ReDoS)에 대한 깊은 인식이 요구됨. 결국 정규 언어는 '작고 빠른 것'을 다루는 데 최적화된 도구이며, 이를 상위 언어 계층과 적절히 조합하여 전체 시스템의 분석 효율을 높이는 것이 설계의 핵심 역량임.
