## 미리 알고가기

- 알파벳 $\Sigma$: 문자열을 만드는 데 쓰는 낱개 기호의 집합임. 예를 들어 이진 문자열이라면 $\Sigma = \{0, 1\}$임
- 문법 $G=(V,\Sigma,P,S)$: 비단말 기호 $V$, 단말 기호 $\Sigma$, 생성 규칙 $P$, 시작 기호 $S$로 이루어져 어떤 문자열이 언어에 속하는지를 규칙으로 정의하는 틀임
- 유한 오토마타(Finite Automaton): 과거 입력 전체를 저장하지 않고 지금 어떤 상태에 있는지만으로 다음 동작을 정하는 상태 기계임. DFA(Deterministic Finite Automaton, 결정적 유한 오토마타)는 한 상태에서 같은 입력에 대해 다음 상태가 하나로 정해지고, NFA(Nondeterministic Finite Automaton, 비결정적 유한 오토마타)는 여러 다음 상태가 동시에 가능함
- Type-3 문법: 언어를 생성 능력 순으로 4단계로 나눈 촘스키 위계(Chomsky Hierarchy)에서 가장 단순한 등급이며, 정규 문법이 여기에 해당함

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 상태 수가 유한한 오토마타만으로 즉시 인식 가능한 문자열 집합이며, 정규 문법은 그 문자열 집합을 만들어내는 Type-3 생성 규칙임. 두 개념은 회전문이 지금 상태만 보고 통과 여부를 즉시 정하듯 판단 가능한 패턴을, 각각 "인식 결과"와 "생성 규칙" 관점에서 부르는 이름임
- **배경/필요성**: 어휘 분석, 패턴 매칭, 입력 검증처럼 입력이 들어올 때마다 즉시 판정해야 하고 이전 기록을 오래 쌓아둘 수 없는 문제에서는, 스택이나 별도 메모리 없이도 판단 가능한 가장 단순한 언어 모델이 필요함

## Ⅱ. 특징

- 상태 기반 처리 구조가 첫 번째 특징임. 별도의 스택이나 지금까지 읽은 입력 기록을 저장하지 않고 오직 현재 어느 상태에 있는지만 알면 다음 동작을 결정할 수 있음. 신호등이 과거에 어떤 색이었는지와 무관하게 지금 켜진 색만 보고 다음 신호를 정하는 것과 같은 원리이며, 이 덕분에 인식기 구현이 단순하고 메모리 사용량이 상태 개수만큼으로 고정됨
- 연산 닫힘 성질(Closure Property)이 두 번째 특징임. 합집합, 연결, 반복(Kleene Star, 클리니 스타) 연산을 적용해도 결과가 항상 정규 언어로 남아 작은 패턴 여러 개를 조합해 복잡한 패턴을 만들어도 안전성이 깨지지 않음. 정규식에서 `|`, 이어붙이기, `*`를 자유롭게 섞어 쓸 수 있는 이유가 여기에 있음
- 선형 시간 처리 성능이 세 번째 특징임. NFA를 DFA로 변환하면 입력 길이 $n$에 대해 시간복잡도가 $O(n)$이 되며, 문자 하나당 상태 전이 한 번만 계산하면 되므로 되돌아가기(백트래킹) 없이 처리 시간을 미리 예측할 수 있음
- 표현력의 한계가 네 번째 특징임. 여는 괄호와 닫는 괄호의 개수가 같아야 하는 조건처럼 지금까지 몇 번 나왔는지를 세어 나중 입력과 맞춰봐야 하는 장거리 의존 구조는, 유한한 상태 수만으로는 그 개수를 저장할 방법이 없어 표현하지 못함. 예를 들어 $a^n b^n$처럼 $a$의 개수만큼 $b$가 뒤따라야 하는 패턴은 정규 언어로 표현할 수 없음

## Ⅲ. 종류 및 비교

- **정규 언어(Regular Language)**: 유한 오토마타가 인식할 수 있는 문자열 집합 그 자체를 가리키며, 문법이 만들어낸 "결과물"에 해당함
- **정규 문법(Regular Grammar)**: 그 문자열 집합을 만들어내는 생성 규칙을 가리키며, Type-3 문법에 해당하는 "생성 규칙"임. 정규 문법이 생성하는 문자열 집합과 유한 오토마타가 인식하는 문자열 집합은 항상 일치하므로, 실무에서는 정규식이 정규 문법 역할을, DFA/NFA가 인식기 역할을 나눠 맡음
- 이 표현 능력이 어디까지인지 판단하려면 한 단계 더 강력한 문맥 자유 언어(Context-Free Language)·문맥 자유 문법(Context-Free Grammar, CFG)과 비교해야 함. 문맥 자유 언어는 PDA(Pushdown Automaton, 푸시다운 오토마타)라는 상태와 스택을 함께 쓰는 기계로 인식하며, 스택 덕분에 정규 언어가 다루지 못하는 중첩 구조까지 처리함

| 판단 기준 | 정규 언어·문법 | 문맥 자유 언어·문법 |
|:---|:---|:---|
| 인식 모델 | DFA, NFA | PDA |
| 기억 구조 | 현재 상태만 유지하는 유한 상태 | 상태에 스택을 더해 지나온 깊이를 기억함 |
| 표현 가능한 구조 | 반복과 선택으로 이뤄진 패턴 | 괄호 중첩처럼 재귀적으로 감싸는 구조 |
| 대표 적용 | 정규식, 어휘 분석기(Lexer) | 구문 분석기(Parser) |

> 요약: 정규 언어·문법은 상태만으로 인식 가능한 반복·선택 패턴을 다루고, 문맥 자유 언어·문법은 스택으로 중첩 구조까지 다룸.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 집합 $Q$ | 입력을 여기까지 읽었다는 판단 지점 전체를 가리키며, 이 집합의 크기가 유한하다는 조건이 정규 언어가 개수를 셀 수 없는 이유를 그대로 결정함 |
| 전이함수 $\delta$ | 현재 상태와 입력 기호 하나를 받아 다음 상태를 정하는 규칙이며, DFA에서는 다음 상태가 하나로, NFA에서는 여러 상태로 동시에 이어짐 |
| 시작 상태 $q_0$·수리 상태(Accepting State) $F$ | 판정의 출발 기준과 종료 기준이며, 입력을 모두 읽었을 때 현재 상태가 $F$에 속해야 그 문자열이 언어에 속한다고 확정함 |
| 생성 규칙 $P$ (우선형 규칙, Right-Linear Rule) | $A \to aB$ 또는 $A \to a$ 형태로만 구성되어 비단말 기호가 항상 규칙 오른쪽 끝에만 남으며, 이 고정된 형태가 상태 전이 하나하나와 그대로 대응함 |

```text
+-------------------+        +-------------------+
| 생성 규칙 P        |  <-->  | 상태 전이 함수 δ   |
| A -> a B          |        | q_A --a--> q_B     |
| B -> b            |        | q_B --b--> q_F     |
+-------------------+        +-------------------+
```

> 요약: 생성 규칙 하나가 상태 전이 하나에 그대로 대응하므로, 정규 문법과 유한 오토마타는 같은 판정 구조를 규칙 표기와 상태 표기로 나눠 표현한 것에 불과함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+      +----------+      +----------+      +----------+
| 입력식별 | ---> | 상태전이 | ---> | 수리판정 | ---> | 결과반환 |
+----------+      +----------+      +----------+      +----------+
```

1. **입력 식별**: 판정 대상 문자열이 알파벳 $\Sigma$에 속하는 기호들로만 이뤄졌는지 확인하고 시작 상태 $q_0$에서 출발함
2. **상태 전이**: 문자를 하나씩 읽을 때마다 전이함수 $\delta$로 다음 상태를 계산하며, 스택이나 별도 저장소 없이 현재 상태값 하나만 갱신함
3. **수리 판정**: 입력을 모두 읽은 시점의 현재 상태가 수리 상태 $F$에 속하는지 확인함
4. **결과 반환**: $F$에 속하면 accept, 아니면 reject를 반환하며, 되돌아가기 없이 한 번의 통과만으로 판정을 끝냄

## Ⅵ. 실무 적용 및 유의점

1. 정규식 기반 어휘 분석기(Lexer)는 토큰 단위 패턴 매칭에는 적합하지만 중첩 괄호나 중첩 태그처럼 개수를 세어 맞춰야 하는 구조는 표현하지 못하므로, 그런 구조가 나오는 지점은 정규식 단계에서 억지로 처리하지 않고 스택 기반 구문 분석기(Parser)로 넘기며 중첩 테스트 케이스 통과율과 파싱 실패 로그로 경계를 확인함
2. 네트워크 침입 탐지나 문자열 필터링에서 NFA를 DFA로 변환해 매칭 시간을 $O(n)$으로 고정할 때 부분집합 구성(Subset Construction) 과정에서 상태 수가 지수적으로 늘어날 수 있으므로, 최소화된 DFA(Minimized DFA)로 다시 줄이고 실제 상태 개수와 메모리 사용량으로 규모를 확인함

## Ⅶ. 결론

정규 언어·문법은 상태 전이만으로 반복·선택 패턴을 $O(n)$에 판정하는 대신 개수를 기억해야 하는 중첩 구조는 표현할 수 없으므로, 어휘 분석처럼 상태만으로 충분한 영역과 구문 분석처럼 스택이 필요한 영역을 구분해 적용해야 함.
