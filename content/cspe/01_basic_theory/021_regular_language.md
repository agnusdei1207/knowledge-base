## 미리 알고가기

- 알파벳($\Sigma$): 문자열을 구성하는 유한한 기호 집합임
- 정규식: 선택, 연결, 반복으로 정규 언어를 간결하게 표현하는 표기임
- 유한 오토마타: 유한한 상태와 입력 기호별 전이로 문자열을 수용하거나 거부하는 모델임
- 클리니 스타($*$): 특정 기호열을 0회 이상 반복함을 나타내는 연산임
- 닫힘성: 합집합, 연결, 반복 연산 후에도 결과가 정규 언어로 남는 성질임

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 유한 오토마타가 상태 전이만으로 인식하는 문자열 집합이며, 정규 문법은 이를 Type-3 생성 규칙으로 표현하는 형식 문법임
- **배경/필요성**: 토큰 추출, 형식 검증, 로그 패턴 매칭처럼 중첩 기억이 필요 없는 문자열 처리는 단순하고 예측 가능한 모델이 필요함

## Ⅱ. 특징

- 현재 상태와 다음 입력 기호만으로 전이가 결정되므로 스택이나 별도 메모리가 필요 없음
- 정규식, 정규 문법, DFA/NFA는 표현 방식만 다르고 같은 언어 범위를 가짐
- 입력 길이에 비례해 한 글자씩 처리하므로 패턴 검사의 처리 시간이 예측 가능함
- 괄호 짝이나 $a^n b^n$처럼 개수를 맞추는 중첩 구조는 표현하지 못함

## Ⅲ. 종류 및 비교

| 표현 방식 | 핵심 역할 | 강점 | 한계 |
|:---|:---|:---|:---|
| 정규식 | 패턴을 연산자로 축약함 | 사람이 규칙을 빠르게 작성함 | 복잡하면 가독성이 급격히 낮아짐 |
| 정규 문법 | 문자열 생성을 규칙으로 정의함 | 형식 언어 분류가 명확함 | 실제 구현에는 변환이 필요함 |
| DFA | 상태별 다음 전이가 하나임 | 실행 시 역추적이 없음 | 변환 과정에서 상태 증가 위험이 있음 |
| NFA | 한 상태에서 여러 전이를 허용함 | 규칙 표현이 간결함 | 실행 전 DFA 변환이나 병렬 추적이 필요함 |

> 요약: 정규식은 작성 표기, 정규 문법은 생성 규칙, 오토마타는 실행 모델로 같은 정규 언어를 다룸.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단말 기호($\Sigma$) | 실제 입력 문자열을 이루는 기호 집합이며 전이의 입력이 됨 |
| 비단말 기호($V$) | 정규 문법에서 상태에 해당하며 다음 생성 규칙 선택을 제한함 |
| 생성 규칙($P$) | $A \rightarrow aB$ 또는 $A \rightarrow a$ 형태로 오른쪽에 비단말을 최대 1개 둠 |
| 시작 기호($S$) | 문자열 생성과 오토마타 초기 상태의 출발점임 |
| 수용 상태 | 입력을 모두 읽은 뒤 문자열이 언어에 속하는지 판정하는 상태임 |

```text
+-----------+     +-------------+     +--------------+
| Pattern   | --> | Grammar/RE  | --> | DFA or NFA   |
+-----------+     +-------------+     +--------------+
                                      |
                                      v
                                +---------------+
                                | Accept/Reject |
                                +---------------+
```

> 요약: 정규 언어는 작성 표기를 오토마타 실행 모델로 바꿔 문자열 수용 여부를 판정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| Read char | --> | Move state | --> | End check | --> | Decide   |
+----------+     +----------+     +----------+     +----------+
```

1. **패턴 정의**: 허용할 문자열 규칙을 정규식이나 정규 문법으로 작성함
2. **모델 변환**: 작성된 규칙을 DFA 또는 NFA의 상태와 전이로 변환함
3. **입력 처리**: 입력 기호를 왼쪽부터 읽고 현재 상태를 전이함
4. **수용 판정**: 입력을 모두 읽은 뒤 수용 상태이면 문자열을 인정함

> 요약: 패턴은 상태 전이로 변환된 뒤 입력을 한 글자씩 소비하며 인정 여부를 결정함.

## Ⅵ. 실무 적용 및 유의점

1. 컴파일러 어휘 분석은 정규 언어로 토큰을 빠르게 구분하되, 괄호 중첩과 블록 구조는 CFG 파서로 넘기고 토큰 오류율로 역할 분리를 확인함
2. 대규모 로그 필터는 정규식으로 빠르게 검사하되, NFA-DFA 변환 시 상태 증가가 크면 규칙을 나누고 메모리 사용량과 처리 지연으로 검증함

## Ⅶ. 결론

- 정규 언어·문법은 기억 없는 문자열 패턴을 선형으로 처리하는 모델이므로, 중첩 구조와 상태 폭증 한계를 기준으로 적용 범위를 정해야 함

## 작성 근거(검토용)

- 개요는 정규 언어, 정규 문법, 유한 오토마타의 동치 관계를 먼저 고정하기 위해 통합 정의로 작성함
- 특징은 기억 없음, 표현 동치, 선형 처리, 중첩 한계로 나누어 선택 기준이 바로 보이게 구성함
- Ⅲ은 정규식·문법·DFA·NFA가 같은 범위를 다루지만 쓰임이 다르므로 표현 방식 비교표로 정리함
- Ⅳ와 Ⅴ는 생성 규칙이 실행 모델로 바뀌는 흐름을 보여주어 어휘 분석 적용과 연결되게 함
- 실무 유의점은 정규식 남용의 대표 실패인 중첩 파싱과 상태 폭증을 검증 지표와 함께 남김
