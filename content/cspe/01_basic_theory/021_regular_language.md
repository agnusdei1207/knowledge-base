# 정규 언어·문법 (Regular Language and Grammar)

## 1. 개요

- **정의/개념**: 정규 언어는 유한 오토마타가 인식할 수 있고 정규 표현식 또는 정규 문법으로 표현 가능한 가장 단순한 형식 언어 계층이다.
- **배경/필요성**: 입력 검증, 토큰 인식, 패턴 검색처럼 제한된 규칙의 문자열 처리는 복잡한 파서보다 정규 언어 모델로 빠르고 명확하게 처리하는 것이 적합하다.

정규 언어는 문자열 패턴을 다루지만 모든 문자열 구조를 표현하지는 못한다. 따라서 강점은 빠른 인식이고 한계는 중첩 구조 표현 불가이다.

## 2. 특징 및 비교

| 구분 | 정규 언어 | 문맥 자유 언어 |
|---|---|---|
| 인식기 | DFA, NFA | Pushdown Automata |
| 표현 방식 | 정규 표현식, 정규 문법 | CFG |
| 메모리 구조 | 유한 상태 | 스택 사용 가능 |
| 적합 대상 | 토큰, 단순 패턴 | 중첩 괄호, 구문 구조 |
| 실무 활용 | lexical analysis, validation | parser, syntax analysis |

정규 언어를 선택할 때는 표현력보다 단순성, 실행 속도, 구현 안정성이 우선인지 확인해야 한다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Alphabet | 언어를 구성하는 기호 집합 | 입력 범위 |
| String | 알파벳 기호의 유한 나열 | 인식 대상 |
| Regular Expression | 문자열 패턴 표현 | union, concat, star |
| Regular Grammar | 우선형 또는 좌선형 생성 규칙 | 유한 상태와 대응 |
| Finite Automata | 문자열 수용 여부 판단 | 구현 모델 |

```text
----------+      +----------+      +----------+
| 정규표현 | ---> | 오토마타 | ---> | 문자열 수용 |
+----------+      +----------+      +----------+
```

표현식, 문법, 오토마타는 서로 변환 가능하므로 한 형태만 외우는 방식보다 동치성과 표현 한계를 함께 이해해야 한다.

## 4. 문제점 및 개선방안

1. **표현력 과신**
   - 정규식으로 중첩 괄호나 문맥 의존 규칙을 처리하려 하면 패턴이 복잡해지고 오류가 생긴다.
   - **개선방안**: 중첩 구조는 CFG와 파서로 분리한다.

2. **정규식 성능 문제**
   - 일부 정규식 엔진은 백트래킹 폭발로 ReDoS 위험이 발생할 수 있다.
   - **개선방안**: DFA 기반 엔진, 패턴 제한, 타임아웃, 정규식 리뷰를 적용한다.

3. **문법과 구현 불일치**
   - 문서상 패턴과 실제 코드의 정규식이 달라지면 검증 결과가 흔들린다.
   - **개선방안**: 테스트 케이스와 패턴 버전 관리를 함께 운영한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 컴파일러 스캐너 | 토큰 패턴을 정규식으로 정의하고 DFA로 변환 | 스캔 시간, 토큰 정확도 |
| 입력값 검증 | 식별자, 전화번호, 코드 값 형식 검증 | 오탐·미탐, 예외율 |
| 로그 필터링 | 정규식으로 이벤트 패턴 탐지 | 처리량, 매칭 지연 |

## 6. 결론

정규 언어는 단순 문자열 패턴을 빠르고 안정적으로 인식하기 위한 형식 언어 계층이다. DFA/NFA/정규 표현식의 동치성과 CFG 대비 한계를 함께 설명해야 선택 기준이 분명해진다.
