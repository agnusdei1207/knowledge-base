## 미리 알고가기

- 알파벳($\Sigma$): 문자열을 구성하는 유한한 기호 집합임
- 정규식: 선택·연결·반복으로 정규 언어를 표현하는 표기임
- 유한 오토마타: 유한한 상태와 입력 기호별 전이로 문자열을 수용하거나 거부하는 모델임
- 결정적 유한 오토마타(DFA): 상태와 입력 기호마다 다음 상태가 하나로 결정되는 유한 오토마타임
- 비결정적 유한 오토마타(NFA): 하나의 상태와 입력에서 다중 전이·$\epsilon$ 전이를 허용하는 유한 오토마타임
- 제3형 문법(Type-3): 생성 규칙을 오른쪽 선형 또는 왼쪽 선형 형태로 제한한 정규 문법임
- $\epsilon$ 전이: 입력 기호를 소비하지 않고 상태만 바꾸는 NFA 전이임
- 문법 기호: $N$은 비단말 집합, $P$는 생성 규칙, $S$는 시작 기호임

## 작성 근거(검토용)

- 개요는 정규 언어·정규 문법·유한 오토마타의 동치 관계를 먼저 확정하기 위해 통합 정의로 작성함
- 특징은 기억 없음·표현 동치·선형 처리·중첩 한계로 나누어 적용 범위와 한계를 구분함
- Ⅲ은 정규식·문법·DFA·NFA가 같은 범위를 다루지만 쓰임이 다르므로 표현·인식 역할 비교표로 정리함
- Ⅳ는 정규 문법의 네 요소와 한 방향 선형 생성 규칙을 제시하고, Ⅴ는 생성 규칙이 인식 모델로 변환되는 흐름을 보여줌
- 정규식 남용의 대표 실패인 중첩 파싱과 상태 폭증을 검증 지표와 함께 남김

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 유한 오토마타가 상태 전이만으로 인식하는 문자열 집합이며, 정규 문법은 정규 언어를 Type-3 생성 규칙으로 표현하는 형식 문법임
- **배경/필요성**: 중첩 구조가 없는 문자열을 상태 전이만으로 판정할 유한 상태 모델이 필요함

### 쉽게 이해하기 (학습용)
- 정규 언어는 미로에서 지나온 길을 기억하지 않고 지금 서 있는 칸만 보고 다음 칸을 정하는 게임과 같고, 정규 문법은 그 게임의 이동 규칙을 적어놓은 설명서임

## Ⅱ. 특징

- 현재 상태와 다음 입력 기호만으로 전이하므로 스택 같은 추가 기억장치가 필요 없음
- 정규식·정규 문법·DFA·NFA는 표현 방식만 다르고 같은 언어 범위를 가짐
- DFA는 입력 기호를 한 번씩 읽어 입력 길이에 비례하는 시간에 문자열을 판정함
- 괄호 짝이나 $a^n b^n$처럼 개수를 맞추는 중첩 구조는 표현하지 못함

### 쉽게 이해하기 (학습용)
- 이 게임은 메모장 없이 지금 위치만 기억하면 되고, 표(문법)로 적든 지도(오토마타)로 그리든 결과는 같은 게임임
- 칸을 한 번씩만 밟고 지나가면 되지만, 괄호 짝처럼 이전에 몇 번 열었는지 세어야 하는 규칙은 이 게임으로 못 만듦

## Ⅲ. 종류 및 비교

| 형태 | 핵심 역할 | 적용 제약 | 대표 활용 |
|:---|:---|:---|:---|
| 정규식 | 선택·연결·반복 연산의 패턴 표기 | 재귀 중첩 표현 불가 | 입력 형식 검증·로그 검색 |
| 정규 문법 | Type-3 생성 규칙으로 문자열 생성 | 비단말 위치·개수 제한 | 토큰 규칙·언어 명세 |
| DFA | 입력 기호별 단일 상태 전이 | NFA 변환 시 상태 수 증가 | 문자열 매칭·프로토콜 검사 |
| NFA | 다중 전이·$\epsilon$ 전이 | 동시 활성 상태 집합 관리 필요 | 정규식 엔진·패턴 설계 |

> 요약: 정규식은 패턴을 표기하고 정규 문법은 문자열을 생성하며 오토마타는 문자열을 인식함.

### 쉽게 이해하기 (학습용)
- 정규식은 게임 규칙을 짧은 기호로 적은 메모, 정규 문법은 규칙을 단계별 설명서로 푼 것, DFA는 정확히 한 길로만 가는 지도, NFA는 여러 길을 동시에 시도해볼 수 있는 지도임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 단말 기호($\Sigma$) | 최종 문자열을 구성하는 기호 집합 |
| 비단말 기호($N$) | 생성 단계를 나타내는 문법 변수 |
| 생성 규칙($P$) | 우선형 $A \rightarrow aB \mid a \mid \epsilon$ 또는 좌선형 $A \rightarrow Ba \mid a \mid \epsilon$ 규칙 |
| 시작 기호($S$) | 문자열 생성을 시작하는 비단말 기호 |

> 요약: 정규 문법은 좌·우 중 한 방향의 선형 생성 규칙으로 단말 문자열을 생성함.

### 쉽게 이해하기 (학습용)
- 단말 기호는 완성된 결과물 조각, 비단말 기호는 아직 덜 만들어진 재료, 생성 규칙은 재료를 조각으로 바꾸는 조리법, 시작 기호는 조리를 시작하는 첫 재료임

## Ⅴ. 원리 및 절차 흐름도

```text
정규식·정규 문법 정의 → 유한 오토마타 변환
                              ↓
입력 기호별 상태 전이 → 입력 종료 후 수용 판정
```

1. **패턴 정의**: 허용할 문자열 규칙을 정규식이나 정규 문법으로 작성함
2. **모델 변환**: 작성된 규칙을 DFA 또는 NFA의 상태와 전이로 변환함
3. **입력 처리**: 입력 기호를 왼쪽부터 읽고 현재 상태를 전이함
4. **수용 판정**: 입력을 모두 읽은 뒤 수용 상태이면 문자열을 인정함

> 요약: 패턴은 상태 전이로 변환된 뒤 입력을 한 글자씩 소비하며 수용 여부를 결정함.

### 쉽게 이해하기 (학습용)
- 규칙을 적고(패턴 정의), 그 규칙을 길찾기 지도로 바꾼 뒤(모델 변환), 글자를 하나씩 읽으며 지도 위를 이동하다가(입력 처리), 도착 지점이 맞으면 통과로 인정함(수용 판정)

## Ⅵ. 실무 사례

1. 컴파일러는 유한 오토마타로 토큰을 인식하고 CFG로 중첩 구문을 분석함
2. 로그 필터는 정규식을 DFA로 변환해 입력을 한 번 읽으며 패턴을 판정함

### 쉽게 이해하기 (학습용)
- 컴파일러가 코드에서 단어 단위를 골라내는 것과, 로그 검색기가 정해진 패턴만 빠르게 걸러내는 것 모두 이 지도찾기 방식을 씀

## Ⅶ. 결론

- 정규 언어는 유한한 상태로 단순 문자열 패턴을 표현하며, 중첩 구조가 필요하면 문맥 자유 문법을 사용해야 함
- 로그 필터·토큰 인식처럼 평면 패턴에 한정해 사용하고, 재귀 문법을 정규식으로 우회 구현하지 말아야 함

### 쉽게 이해하기 (학습용)
- 단순한 패턴은 이 방식으로 충분하지만 중첩 구조가 필요하면 다른 도구(문맥 자유 문법)로 바꿔야지, 억지로 짧은 규칙만으로 흉내 내면 안 됨
