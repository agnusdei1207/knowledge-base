## 미리 알고가기

- 알파벳($\Sigma$): 문자열을 구성하는 유한한 기호 집합임
- 정규식: 선택·연결·반복으로 정규 언어를 표현하는 표기임
- 유한 오토마타: 유한한 상태와 입력 기호별 전이로 문자열을 수용하거나 거부하는 모델임
- 결정적 유한 오토마타(DFA): 상태와 입력 기호마다 다음 상태가 하나로 결정되는 유한 오토마타임
- 비결정적 유한 오토마타(NFA): 하나의 상태와 입력에서 다중 전이·$\epsilon$ 전이를 허용하는 유한 오토마타임
- 제3형 문법(Type-3): 우변을 단말 1개와 비단말 1개 이하로 제한한 정규 문법임
- $\epsilon$ 전이: 입력 기호를 소비하지 않고 상태만 바꾸는 NFA 전이임
- 문법 기호: $N$은 비단말 집합, $P$는 생성 규칙, $S$는 시작 기호임

## 작성 근거(검토용)

- 개요는 정규 언어·정규 문법·유한 오토마타의 동치 관계를 먼저 확정하기 위해 통합 정의로 작성함
- 특징은 기억 없음·표현 동치·선형 처리·중첩 한계로 나누어 적용 범위와 한계를 구분함
- Ⅲ은 정규식·문법·DFA·NFA가 같은 범위를 다루지만 쓰임이 다르므로 표현·인식 역할 비교표로 정리함
- Ⅳ와 Ⅴ는 생성 규칙이 인식 모델로 변환되는 흐름을 보여주어 어휘 분석 적용과 연결되게 함
- 정규식 남용의 대표 실패인 중첩 파싱과 상태 폭증을 검증 지표와 함께 남김

## Ⅰ. 개요

- **정의/개념**: 정규 언어는 유한 오토마타가 상태 전이만으로 인식하는 문자열 집합이며, 정규 문법은 이를 Type-3 생성 규칙으로 표현하는 형식 문법임
- **배경/필요성**: 중첩 구조가 없는 문자열을 상태 전이만으로 판정할 유한 상태 모델이 필요함

## Ⅱ. 특징

- 현재 상태와 다음 입력 기호만으로 전이가 결정되므로 스택이나 별도 메모리가 필요 없음
- 정규식·정규 문법·DFA·NFA는 표현 방식만 다르고 같은 언어 범위를 가짐
- DFA는 입력 기호를 한 번씩 읽어 입력 길이에 비례하는 시간에 문자열을 판정함
- 괄호 짝이나 $a^n b^n$처럼 개수를 맞추는 중첩 구조는 표현하지 못함

## Ⅲ. 종류 및 비교

| 형태 | 핵심 역할 | 적용 제약 | 대표 활용 |
|:---|:---|:---|:---|
| 정규식 | 선택·연결·반복 연산의 패턴 표기 | 재귀 중첩 표현 불가 | 입력 형식 검증·로그 검색 |
| 정규 문법 | Type-3 생성 규칙으로 문자열 생성 | 비단말 위치·개수 제한 | 토큰 규칙·언어 명세 |
| DFA | 입력 기호별 단일 상태 전이 | NFA 변환 시 상태 수 증가 | 문자열 매칭·프로토콜 검사 |
| NFA | 다중 전이·$\epsilon$ 전이 | 상태 집합 추적 | 정규식 엔진·패턴 설계 |

> 요약: 정규식은 패턴을 표기하고 정규 문법은 문자열을 생성하며 오토마타는 문자열을 인식함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단말 기호($\Sigma$) | 입력 문자열·상태 전이의 기호 집합 |
| 비단말 기호($N$) | 생성 단계를 나타내는 문법 변수 |
| 생성 규칙($P$) | $A \rightarrow aB$ 또는 $A \rightarrow a$ 치환 규칙 |
| 시작 기호($S$) | 문자열 생성을 시작하는 비단말 기호 |

> 요약: 정규 문법은 시작 기호를 생성 규칙으로 치환해 단말 문자열을 생성함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +-----------+     +----------+     +----------+
| 패턴 정의 | --> | 오토마타 변환 | --> | 입력·전이 | --> | 수용 판정 |
+----------+     +-----------+     +----------+     +----------+
```

1. **패턴 정의**: 허용할 문자열 규칙을 정규식이나 정규 문법으로 작성함
2. **모델 변환**: 작성된 규칙을 DFA 또는 NFA의 상태와 전이로 변환함
3. **입력 처리**: 입력 기호를 왼쪽부터 읽고 현재 상태를 전이함
4. **수용 판정**: 입력을 모두 읽은 뒤 수용 상태이면 문자열을 인정함

> 요약: 패턴은 상태 전이로 변환된 뒤 입력을 한 글자씩 소비하며 수용 여부를 결정함.

## Ⅵ. 실무 사례

1. 컴파일러는 유한 오토마타로 토큰을 인식하고 CFG로 중첩 구문을 분석해 오류 위치를 구분함
2. 로그 필터는 정규식별 DFA 상태 수를 제한하고 메모리 사용량·처리 지연을 확인함

## Ⅶ. 결론

- 정규 문법은 유한 오토마타와 같은 언어를 표현하므로 중첩 구조와 상태 수 증가를 기준으로 적용 범위를 정해야 함
