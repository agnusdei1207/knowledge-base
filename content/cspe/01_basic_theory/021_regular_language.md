# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 정규 언어(Regular Language)는 촘스키 위계에서 **가장 단순한 최하위 언어 계층(Type-3)**으로, 유한 오토마타(020 참조)가 인식할 수 있고 정규 문법(Regular Grammar)으로 생성할 수 있는 문자열들의 집합이다.
- **왜 필요한가**: 컴파일러가 소스 코드를 토큰으로 쪼개거나, 방화벽이 패킷 패턴을 검사할 때는 기억력이 필요 없는 가장 빠른 판정 규칙이 필요하다. 정규 언어는 상태 하나만 기억하면 되므로 O(N) 시간에 판정할 수 있다.
- **핵심 직관**: 정규 언어는 "지금 상태"만 기억하는 기계가 처리할 수 있는 언어다. "지금까지 괄호를 몇 개 열었는지" 같은 개수 세기는 못 한다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 촘스키 위계 (Chomsky Hierarchy) | 문법을 생성 규칙의 제약 강도에 따라 Type 0~3의 4단계로 분류한 체계 | 언어의 난이도 리그(1부~4부) |
| 정규 언어 (Regular Language, Type-3) | 유한 오토마타로 인식 가능한 문자열 집합 — 촘스키 위계 최하위(가장 단순) | 4부 리그(가장 기본 규칙) |
| 정규 문법 (Regular Grammar) | 생성 규칙이 "비단말 1개 + 단말 1개" 형태로 극도로 제한된 문법 | "한 글자 쓰고 다음 상태로" 규칙만 있는 매뉴얼 |
| 우측 선형 문법 (Right Linear Grammar) | 비단말 기호가 항상 규칙의 맨 오른쪽에만 오는 정규 문법 | 오른쪽으로만 이어 붙이는 구슬 꿰기 |
| 좌측 선형 문법 (Left Linear Grammar) | 비단말 기호가 항상 규칙의 맨 왼쪽에만 오는 정규 문법 | 왼쪽으로만 이어 붙이는 구슬 꿰기 |
| 정규 표현식 (Regular Expression) | 합집합·연접·클린 스타(반복)로 정규 언어를 기술하는 표기법 — 정규 문법·유한 오토마타와 동치 | 패턴을 적는 축약 악보 |
| 펌핑 정리 (Pumping Lemma) | 어떤 언어가 정규 언어가 아님을 증명하는 도구 — 충분히 긴 문자열의 특정 부분을 반복(pump)해도 여전히 그 언어에 속해야 한다는 필요조건 | "늘려도 규칙에 맞아야 진짜"라는 반증 시험 |

## 깊이 이해

### 정규 문법 생성 규칙이 왜 이렇게 좁은가 — 유한 오토마타와의 1:1 대응
- 우측 선형 규칙(예: A→aB, A→a)은 "지금 상태 A에서 글자 a를 소비하고 상태 B로 간다"는 DFA·NFA의 전이 규칙을 문법 표기로 그대로 옮긴 것과 같다. 비단말(상태)이 항상 우변 끝에 하나만 남기 때문에, 파생 과정이 왼쪽에서 오른쪽으로 한 줄기로만 뻗는다 — 가지가 갈라지지 않는다.
- 대조: 문맥 자유 문법(022 참조)은 비단말이 단말 사이에 낄 수 있어(예: A→aBb) 양쪽으로 동시에 자라는 트리를 만들 수 있다. 이 차이가 "스택 메모리 없이 표현 가능한가"의 경계선이다.

### 펌핑 정리로 한계를 실제로 증명하기 — a를 n개, b를 n개 이어붙인 언어
- 주장: L = "a를 n개 쓰고 이어서 b를 n개 쓴 문자열 전체(n≥0)"는 정규 언어가 아니다.
- 증명: L이 정규 언어라고 가정하면 펌핑 길이 p가 존재해, 길이 p 이상인 모든 문자열 w는 w=xyz로 쪼개져 y의 길이가 1 이상이고, xy 전체 길이는 p 이하이며, y를 몇 번을 반복해 넣어도(펌핑해도) 여전히 L에 속해야 한다.
- w로 "a를 p개, b를 p개" 이어붙인 문자열을 고르면, xy 길이가 p 이하라는 조건 때문에 y는 반드시 a로만 구성된다(앞쪽 p개가 전부 a이므로). y가 a를 k개(k≥1) 포함한다고 하면, y를 한 번 더 추가한 문자열은 a가 (p+k)개, b는 그대로 p개가 되어 a 개수와 b 개수가 달라진다 — 이는 L에 속하지 않는다. "y를 펌핑해도 여전히 L에 속해야 한다"는 전제와 모순되므로, L은 정규 언어가 아니다.
- 이것이 "정규 언어는 개수를 셀 수 없다(카운팅 불가)"는 성질의 수학적 증거다. 상태가 유한하므로 아무리 길게 읽어도 같은 상태를 순환(반복)할 수밖에 없고, 그 반복 구간을 늘리거나 줄여도 언어 소속이 바뀌지 않아야 하는데, 개수를 정확히 세야 하는 언어는 이 조건을 깬다.

### 실무에서 정규 언어의 한계가 문제 되는 순간
- 정규식으로 HTML 태그의 중첩 짝(`<div><span></span></div>`)을 완벽히 검증하려는 시도는 이론적으로 실패한다 — 중첩 깊이를 세야 하므로 정규 언어의 표현력을 벗어난다(문맥 자유 문법 필요, 022 참조).
- 반면 IP 주소 형식처럼 "개수를 셀 필요 없는" 고정 패턴은 정규식으로 완벽히 처리된다.

### 비유
- 구슬 꿰기에 비유하면, 빨간 구슬이든 파란 구슬이든 원하는 순서로 꿸 수는 있지만 "빨간 구슬을 꿴 개수만큼 파란 구슬을 꿰라"는 규칙은 정규 문법으로 표현할 수 없다 — 지금까지 몇 개 꿰었는지 기억할 저장소가 없기 때문이다.

## 연결 개념
- 유한 오토마타(DFA·NFA) — 정규 언어를 인식하는 기계 모델 (020 참조)
- 문맥 자유 문법 — 정규 언어의 상위 계층으로, 스택을 더해 카운팅·중첩을 가능하게 함 (022 참조)
- 정규식↔정규 문법↔유한 오토마타의 동치 관계와 실무 변환 파이프라인 — 021_regular_language_and_grammar 참조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 촘스키 위계 중 Type-3에 해당하는 극단적 제약 문법으로, 비단말 기호가 최좌측 또는 최우측 끝에 단 1개만 나타나는 선형 구조 언어다.
> 2. **가치**: 메모리 스택 없이 1차원 상태 전이만으로 $O(N)$ 매칭이 가능하여, 컴파일러 어휘 분석(Lexical Analysis)과 방화벽 패킷 고속 필터링의 코어 엔진이 된다.
> 3. **판단 포인트**: 펌핑 정리(Pumping Lemma) 증명에 의해 "카운팅" 능력이 없음이 확인되므로, 구문 파싱(Syntax Parser) 단계로는 스케일업(Scale-up)할 수 없다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 촘스키 위계 내 정규 언어 위상 | Type-3, 정규식, 유한 오토마타(FSA) 매핑 3원칙 | 구문 분석(Parsing)에 쓰인다는 치명적 오답 |
| 정규 문법의 수학적 생성 규칙 이해 | 우측 정규 / 좌측 정규 제한 조건 수식화 | 생성 규칙의 제약을 무시하고 아무 문자열이나 나열 |

> 요약: 정규 언어는 표현할 수 있는 구조적 깊이를 포기한 대가로, 하드웨어 회로나 1차원 맵으로 즉시 컴파일 가능한 초고속 성능을 확보했다.

## Ⅰ. 개요 및 필요성

- 정의: 유한 오토마타(FSA)로 인식 및 수용 가능하며, 정규 표현식으로 기술 가능한 선형 구조 문자열 집합(Type-3 언어)
- 배경: 컴파일러 설계 시 프로그램 코드를 빠르고 일관되게 토큰(키워드, 식별자) 단위로 분리할 기계적 장치 요구
- 필요성: 스택 메모리 점유 없이 $O(N)$ 런타임에 로그 파싱, DPI(Deep Packet Inspection) 등 단순 패턴 매칭을 와이어 스피드로 수행하기 위해 필수

## Ⅱ. 촘스키 위계 및 구성요소 (4튜플)

```text
Type 0: 튜링 머신 ⊃ Type 1: 문맥 의존(LBA) ⊃ Type 2: 문맥 자유(PDA) ⊃ Type 3: 정규 언어(DFA/NFA)
```

| 기호 (4튜플 $G = (V, T, S, P)$) | 역할 및 의미 | 실무 제약 사항 |
|:---|:---|:---|
| $V$ (Non-terminals) | 비단말 기호 집합 (대문자 $A, B$) | 다른 기호로 치환될 수 있는 중간 상태 변수 |
| $T$ (Terminals) | 단말 기호 집합 (소문자 $a, b$) | 더 이상 쪼개지지 않는 최종 고정 문자(토큰) |
| $S$ (Start Symbol) | 문법 파생이 시작되는 최초 루트 비단말 기호 | $S \in V$ (시작점 고정) |
| $P$ (Productions) | $V \rightarrow (V \cup T)^*$ 형태의 단방향 치환 규칙 | 정규 문법은 이 $P$의 형태를 극단적으로 제약함 |

> 요약: 정규 언어의 본질은 단말 기호($T$)와 비단말 기호($V$)를 결합하는 생산 규칙($P$)에 매우 엄격한 수학적 족쇄를 채웠다는 데 있다.

## Ⅲ. 정규 문법 생성 규칙(Production) 제한 흐름도

```text
정규 문법 = [우측 선형 문법] OR [좌측 선형 문법] (두 가지를 한 문법에 혼용하면 정규성 파괴됨)
```

| 문법 종류 | 생성 규칙 허용 형태 | 검증 기준 (특징) |
|:---:|:---|:---|
| 우측 선형 (Right Linear) | $A \rightarrow aB$ 또는 $A \rightarrow a$ (비단말 맨 우측 고정) | 파생될 트리가 항상 오른쪽 일방향으로만 가지를 침 |
| 좌측 선형 (Left Linear) | $A \rightarrow Ba$ 또는 $A \rightarrow a$ (비단말 맨 좌측 고정) | 파생될 트리가 항상 왼쪽 일방향으로만 가지를 침 |
| **위반 사례 (문맥자유)** | $A \rightarrow aBb$ (단말 문자들 사이에 비단말 삽입) | 양방향 파생이 발생하여 상태 복귀를 위한 스택 메모리 필요 |

> 요약: 비단말 기호가 한쪽 끝에만 위치하도록 강제하는 것은, "다음 상태로 넘어갈 때 이전 상태를 LIFO 스택에 저장할 필요를 수학적으로 제거"하는 메커니즘이다.

## Ⅴ. 심화 비교 판단 (정규 언어 한계 증명: 펌핑 정리)

| 비교 축 | 정규 언어 수용 가능 패턴 | 수용 불가 패턴 (한계) | 이론적 한계 기준 |
|:---|:---|:---|:---|
| 문자열 매칭 | `a*b*` (a 0개 이상, 이후 b 0개 이상) | `a^n b^n` (a 개수와 **정확히 동일한** 개수의 b) | 상태 간 카운팅(기억력) 부재 |
| 구조 검증 | 짝수 개의 0과 홀수 개의 1 구조 | `( ( ) )` 같은 중첩 깊이가 있는 괄호 쌍 매칭 | 트리 깊이 추적(LIFO) 부재 |
| 연산 능력 | 1차원 순차 매칭 및 유한 루프 | 팰린드롬(회문, 기러기) 문자 구조 식별 | 문자열 역탐색 위한 메모리 부재 |

> 요약: 펌핑 정리(Pumping Lemma)로 유한 상태의 순환 사이클을 증명해 보면, $a^n b^n$ 같은 동기화 개수 매칭은 정규 언어 울타리를 벗어남이 즉각 판명된다.

| 리스크 | 발생 원인 | 대응 기법 (아키텍처 스위칭) | 확인 지표 |
|:---|:---|:---|:---|
| 정규식 백트래킹 지수 폭발 | PCRE 등 엔진에서 `(a+)+` 중첩 수량자에 실패 문자열 매칭 시 탐색 트리가 $O(2^N)$ 으로 재귀 폭발 | 런타임 엔진을 재귀 백트래킹(NFA) 기반에서 비재귀 톰슨 상태 전이(DFA) 기반 엔진(RE2 등)으로 강제 교체 | Regex CPU 점유율 스파이크 100% 지속 |
| 표현력 초과 요구 오적용 | 괄호 중첩·카운팅이 필요한 요구를 정규식만으로 해결하려 시도 | 요구 분석 단계에서 펌핑 정리 기준으로 정규 언어 표현 가능 여부 사전 판별 | 설계 리뷰 시 CFG 전환 필요성 검토 완료 여부 |

> 요약: 정규 언어 적용 리스크는 백트래킹 폭발과 표현력 초과 오적용이며, DFA 엔진 전환과 사전 표현력 판별로 통제한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 어휘 분석기(Lex/Flex): 소스 코드를 읽어 들일 때 스페이스/주석을 무시하고, 정규 언어 기반 DFA 상태 전이를 거쳐 `if`, `while`, 변수명 등을 토큰(Token) 스트림으로 고속 변환
2. 네트워크 페이로드 DPI 필터링: Suricata, Snort 방화벽에서 기가비트급 실시간 패킷의 바이트 배열을 스캔하여, 정규식 기반 악성 시그니처 룰셋 1만 개를 병합된 DFA 전이 테이블(Aho-Corasick)로 동시 매칭
3. 대규모 데이터 파이프라인 정제 전처리: ELK 스택(Logstash) 로그 파이프라인에서 정규 언어(Grok) 필터를 적용, 비정형 Apache 텍스트 로그를 IP/시간/에러코드의 정형 JSON으로 초당 수만 건 분해 추출

**결론 (2줄):**
- 기술사 판단: 정규 언어는 표현할 수 있는 구조적 깊이를 깎아내는 뼈를 깎는 제약 대신, 메모리 풋프린트 없는 100% 결정론적 선형 속도를 쟁취한 코어 엔진이다.
- 향후 방향: 최근 대형 언어 모델(LLM) 환경에서도, 환각(Hallucination)이 섞인 출력을 통제하기 위해 빠르고 확정적인 정규식 기반 가드레일을 1차 안전 필터로 융합 적용 중이다.
