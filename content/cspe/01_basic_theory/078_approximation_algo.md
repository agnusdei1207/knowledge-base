## 미리 알고가기

- 최적해: 목적 함수를 최적으로 만드는 해임
- 근사해: 최적해는 아니지만 허용 가능한 품질을 가진 해임
- 근사비: 알고리즘 해가 최적해와 얼마나 떨어질 수 있는지 나타내는 보장값임
- 휴리스틱: 경험 규칙으로 해를 탐색하지만 일반적인 품질 경계를 보장하지 않는 방법임
- 완화(Relaxation): 어려운 제약을 풀어 계산하기 쉬운 문제로 바꾸는 방법임
- LP 완화: 정수 변수 조건을 연속 변수로 풀어 최적해의 경계를 구하는 선형계획 완화임

## 작성 근거(검토용)

- 개요는 NP-난해, 다항 시간, 품질 보장을 함께 제시해 근사 알고리즘의 존재 이유를 정의함
- 특징은 최악 경계, 정확/휴리스틱 대비, 대표 기법, 구현 비용을 선택 판단 기준으로 선정함
- Ⅲ은 정확 알고리즘·휴리스틱과 비교해 근사 알고리즘의 중간 위치를 명확히 함
- Ⅴ는 완화·탐욕에서 실행 가능 해와 근사비 증명으로 이어지는 절차를 중심으로 배치함
- 근사비만으로 운영 품질을 판단할 수 없어 계산 시간과 자원 사용량을 함께 제시함

## Ⅰ. 개요

- **정의/개념**: 근사 알고리즘은 NP-난해 최적화 문제에서 다항 시간 내에 근사비가 보장된 해를 찾는 알고리즘임
- **배경/필요성**: 계산 시간 한도 안에서 최적해와의 품질 차이를 제한하기 위해 근사비가 보장된 알고리즘이 필요함

## Ⅱ. 특징

- 다항 시간에 실행 가능한 해를 구하고 최적해 대비 최악 근사비를 보장함
- 탐욕, LP 완화, 라운딩, 지역 탐색을 문제 구조에 맞게 사용함
- 근사비는 해 품질 경계만 나타내므로 상수 연산량과 구현 비용을 별도로 확인해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정확 알고리즘 | 근사 알고리즘 | 휴리스틱 |
|:---|:---|:---|:---|
| 해 품질 | 최적해 보장 | 최악 근사비 보장 | 일반적인 최악 품질 경계 없음 |
| 실행 시간 | NP-난해 일반 입력에서 지수 시간 가능 | 다항 시간 보장 | 문제와 구현에 따라 달라짐 |
| 대표 적용 사례 | 정수 계획의 정확해 계산 | 거리 삼각부등식을 만족하는 외판원 문제(TSP)·집합 덮개 | 실시간 스케줄링·경로 탐색 |
| 적합 조건 | 최적성 증명이 필요하고 계산 시간 한도를 충족 | 다항 시간과 근사비 보장이 모두 필요 | 이론적 품질 보장보다 응답 시간과 경험 규칙이 우선 |

> 요약: 정확해 계산이 시간 한도를 넘고 휴리스틱에 품질 경계가 없을 때 근사 알고리즘을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 목적 함수 | 최소화 또는 최대화할 비용·효용 기준임 |
| 제약 조건 | 해가 만족해야 하는 자원·용량·순서 제한임 |
| 근사비 $\rho$ | 최악 입력에서도 보장되는 해 품질 한계임 |
| 완화 해 | 어려운 정수 제약을 풀어 얻은 중간 해임 |
| 라운딩 규칙 | 완화 해를 실제 가능한 해로 바꾸는 기준임 |

> 요약: 근사 알고리즘은 다항 시간 후보 해와 근사비 증명을 함께 제공해야 휴리스틱과 구분됨.

## Ⅴ. 원리 및 절차 흐름도

```text
문제 수식화 -> 완화·탐욕 적용 -> 실행 가능 해 구성 -> 최적해 경계 비교 -> 근사비 증명
```

1. **문제 수식화**: 목적 함수와 제약을 명확히 정의함
2. **근사해 구성**: 탐욕, 완화, 라운딩으로 다항 시간 안에 후보 해를 구함
3. **실행 가능성 확인**: 라운딩한 해가 원래 문제의 제약을 만족하는지 확인함
4. **품질 증명**: 후보 해와 최적해 경계의 최악 비율을 계산함

> 요약: 근사 알고리즘은 다항 시간에 실행 가능 해를 만들고 최적해 경계와 비교해 근사비를 증명함.

## Ⅵ. 실무 사례

1. 데이터센터 가상머신 배치는 근사 알고리즘을 적용하고 최적해 대비 사용 서버 수·계산 시간으로 검증함
2. 컨테이너 스케줄링은 탐욕 근사·지역 탐색을 적용하고 자원 사용률·p95 배치 지연으로 검증함

## Ⅶ. 결론

- 근사 알고리즘은 최적해 계산 시간과 해 품질 사이에서 증명 가능한 근사비로 해를 선택하는 방법임
