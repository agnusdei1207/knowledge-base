## 미리 알고가기

- 최적해: 목적 함수를 최소화 또는 최대화하는 해임
- 근사해: 최적해는 아니지만 허용 가능한 품질을 가진 해임
- 근사비 $\rho$: 최소화 문제는 $\text{ALG}/\text{OPT} \le \rho$로, 최대화 문제는 $\text{ALG}/\text{OPT} \ge \rho$로 정의하는 최악 품질 보장값임
- 근사 스킴(PTAS/FPTAS): 오차 $\varepsilon$마다 $(1+\varepsilon)$ 근사해를 구하는 PTAS 중 수행 시간이 $1/\varepsilon$에도 다항인 경우를 FPTAS라 함
- 휴리스틱: 경험 규칙으로 해를 탐색하지만 일반적인 품질 경계를 보장하지 않는 방법임
- 완화(Relaxation): 어려운 제약을 풀어 계산하기 쉬운 문제로 바꾸는 방법임
- 선형계획 완화(LP 완화): 정수 조건을 연속값 조건으로 풀어 최적해의 경계를 구하는 방식임
- 최초 적합 감소(First Fit Decreasing): 항목을 크기순으로 정렬하고 들어갈 수 있는 첫 용기에 배치하는 근사 기법임
- 라운딩(Rounding): 연속 변수로 구한 해를 정수 조건에 맞는 해로 바꾸는 절차임
- 선형계획 경계(LP Bound): 선형계획 완화가 제공하는 최적 목적값의 상한 또는 하한임

## 작성 근거(검토용)

- 개요는 NP-난해, 다항 시간, 품질 보장을 함께 제시해 근사 알고리즘의 존재 이유를 정의함
- 특징은 최악 경계, 대표 기법, 구현 비용, PTAS·FPTAS 세분화를 선택 판단 기준으로 선정함
- Ⅲ은 정확 알고리즘·휴리스틱과 비교해 근사 알고리즘의 중간 위치를 명확히 함
- Ⅴ는 완화·탐욕에서 실행 가능 해와 근사비 증명으로 이어지는 절차를 중심으로 배치함
- 근사비만으로 운영 품질을 판단할 수 없어 계산 시간과 자원 사용량을 함께 제시함

## Ⅰ. 개요

- **정의/개념**: 근사 알고리즘은 NP-난해 최적화 문제에서 다항 시간 내에 근사비가 보장된 해를 찾는 알고리즘임
- **배경/필요성**: NP-난해 문제는 다항 시간에 정확한 최적해를 구할 수 없으므로 품질 보장 대안이 필요함

## Ⅱ. 특징

- 다항 시간에 실행 가능한 해를 구하고 최적해 대비 최악 근사비를 보장함
- 탐욕, LP 완화, 라운딩, 지역 탐색을 문제 구조에 맞게 사용함
- 근사비는 해 품질 경계만 나타내므로 실제 실행 시간과 구현 비용을 별도로 확인해야 함
- 오차 $\varepsilon$마다 근사비를 좁히는 PTAS와 $1/\varepsilon$까지 다항 시간인 FPTAS로 세분화함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정확 알고리즘 | 근사 알고리즘 | 휴리스틱 |
|:---|:---|:---|:---|
| 탐색 메커니즘 | 최적해 탐색 | 근사비 보장 탐색 | 경험 규칙 탐색 |
| 해 품질 | 최적해 보장 | 최악 근사비 보장 | 품질 경계 없음 |
| 주요 리스크 | 지수 시간 | 느슨한 근사비 | 품질 변동 |

> 요약: 정확한 해의 계산이 시간 한도를 넘고 휴리스틱에 품질 경계가 없을 때 근사 알고리즘을 선택함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 목적 함수 | 최소화·최대화할 비용·효용 기준 |
| 제약 조건 | 해가 지켜야 하는 자원·용량·순서 제한 |
| 근사비 $\rho$ | 최악 입력의 해 품질 보장값 |
| 완화 해 | 정수 제약을 푼 연속형 중간 해 |
| 라운딩 규칙 | 완화 해를 실행 가능 해로 바꾸는 기준 |

> 요약: 근사 알고리즘은 다항 시간 후보 해와 근사비 증명을 함께 제공해야 휴리스틱과 구분됨.

## Ⅴ. 원리 및 절차 흐름도

```text
문제 수식화 -> 근사해 구성 -> 실행 가능성 확인 -> 품질 증명
```

1. **문제 수식화**: 목적 함수와 제약을 명확히 정의함
2. **근사해 구성**: 탐욕, 완화, 라운딩으로 다항 시간 안에 후보 해를 구함
3. **실행 가능성 확인**: 구성한 후보 해가 원래 문제의 제약을 만족하는지 확인함
4. **품질 증명**: 후보 해와 최적해 경계의 최악 비율을 계산함

> 요약: 근사 알고리즘은 다항 시간에 실행 가능 해를 만들고 최적해 경계와 비교해 근사비를 증명함.

## Ⅵ. 실무 사례

1. 데이터센터 가상머신 배치는 First Fit Decreasing을 적용하고 소규모 최적해 대비 사용 서버 수로 근사비를 가늠함
2. 컨테이너 배치는 LP 완화·라운딩을 적용하고 LP 하한 대비 사용 노드 수로 근사비 수준을 판단함

## Ⅶ. 결론

- 근사 알고리즘은 최적해 계산이 어려울 때 실행 시간을 줄이는 대신, 보장 가능한 범위에서 해의 품질을 양보함
