## 미리 알고가기

- 최적해 `OPT`: 목적 함수 기준으로 최소 또는 최대가 되는 해의 값임
- 근사해 `ALG`: 알고리즘이 제한 시간 안에 산출한 해의 값임
- 근사비: `ALG`가 `OPT`에서 얼마나 벗어나는지 보장하는 비율임
- 최소화 문제: 비용을 줄이는 문제이며 보통 `ALG/OPT <= ρ`로 근사비를 봄
- 최대화 문제: 이익을 키우는 문제이며 보통 `OPT/ALG <= ρ`로 근사비를 봄
- 휴리스틱: 수학적 품질 보장 없이 경험적으로 허용 품질의 해를 찾는 방법임

## Ⅰ. 개요

- **정의**: 근사 알고리즘은 어려운 최적화 문제에서 다항 시간 안에 최적해와의 차이가 보장 범위 안인 해를 산출하는 알고리즘임
- **배경/필요성**: 물류 경로, 작업 스케줄링, 네트워크 설계처럼 최적해 탐색 공간이 큰 문제는 실무 의사결정 시간 안에 허용 품질 이상의 해가 필요함
- **비유**: 최단 경로를 완벽히 찾지는 못해도 최악의 경우에도 기준 거리의 1.5배 안에 드는 길을 보장하는 내비게이션과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 근사와 휴리스틱 차이 설명 | 근사비의 수학적 보장 | 경험적 성능만으로 근사 알고리즘이라 서술 |
| 다항시간 근사 스킴(Polynomial-Time Approximation Scheme, PTAS)/완전 다항시간 근사 스킴(Fully Polynomial-Time Approximation Scheme, FPTAS) 이해 | 정확도 `ε`와 시간 복잡도 관계 | PTAS와 FPTAS 구분 누락 |

> 요약: 근사 알고리즘은 최적해를 포기하는 대신 다항 시간과 품질 보장을 함께 제공하는 최적화 해법임

## Ⅱ. 특징/비교

| 판단 기준 | 정확 알고리즘 | 근사 알고리즘 | 휴리스틱 |
|:---|:---|:---|:---|
| 해 품질 | 최적해를 보장함 | 최적해 대비 근사비를 보장함 | 보장이 없고 경험적 성능에 의존함 |
| 시간 특성 | NP-Hard 문제에서 지수 시간이 될 수 있음 | 다항 시간 실행을 목표로 함 | 평균 실행 시간은 짧으나 최악 실행 시간을 보장하지 못함 |
| 신뢰 근거 | 완전 탐색 또는 엄밀한 최적화 | 수학적 근사비 증명 | 실험 결과와 도메인 경험 |
| 선택 기준 | 입력이 작거나 정확성이 필수 | 품질 보장과 시간 제한이 모두 필요 | 빠른 실험과 복잡한 현실 제약 |

> 요약: 근사 알고리즘은 정확 알고리즘과 휴리스틱 사이에서 시간과 품질 보장을 균형화하는 선택지임

- **상수 근사**: 문제 크기와 무관한 근사비를 보장해 실무 설명이 쉬움
- **PTAS**: 임의의 `ε`에 대해 `1+ε` 근사를 제공하지만 `1/ε`에 대한 시간이 클 수 있음
- **FPTAS**: 입력 크기와 `1/ε` 모두에 대해 다항 시간인 더 강한 근사 스킴임

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Optimization| ---> | Relaxation  | ---> | Polynomial  |
| Problem     |      | or Greedy   |      | Algorithm   |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Approx Sol  | ---> | Ratio Proof | ---> | Decision    |
| ALG         |      | ALG vs OPT  |      | Use / Tune  |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 목적 함수 | 최소화 또는 최대화할 비용·이익 기준을 수식으로 정의함 | 점수판 |
| 하한·상한 | 최적해와 비교할 기준값을 선형계획 완화(Linear Programming Relaxation, LP relaxation), dual, greedy bound 등으로 확보함 | 기준선 |
| 다항 알고리즘 | greedy, LP rounding, primal-dual 등 제한 시간 안에 해를 만드는 절차임 | 풀이 도구 |
| 근사해 | 알고리즘이 산출한 실제 실행 가능한 해임 | 제출 답안 |
| 근사비 증명 | 최적해와 근사해의 차이가 일정 비율 이내임을 보이는 논리임 | 품질 보증서 |

> 요약: 근사 알고리즘은 문제 모델, 비교 기준, 다항 절차, 근사해, 근사비 증명으로 구성됨

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Model     | --> | Bound     | --> | Construct | --> | Prove     |
| Problem   |     | OPT       |     | ALG       |     | Ratio     |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
ILP/graph          lower/upper        feasible sol       rho guarantee
```

1. **문제 모델링**: 그래프, 정수계획, 집합 커버 등으로 입력과 목적 함수를 명확히 표현함
2. **비교 기준 확보**: 최적해의 하한 또는 상한을 수학적으로 구해 근사비 증명의 기준을 만듦
3. **근사해 구성**: 탐욕 선택, 이완 후 라운딩, primal-dual 등으로 실행 가능한 해를 다항 시간에 생성함
4. **근사비 증명**: `ALG`와 `OPT`의 관계를 부등식으로 보여 최악의 경우 품질 보장을 제시함

> 요약: 근사 알고리즘은 최적화 문제를 모델링하고 비교 기준을 세운 뒤 해를 구성하고 근사비로 품질을 증명함

## Ⅴ. 문제점 및 개선방안

- **P1 근사비 증명 난도**: 문제 구조에 맞는 하한·상한을 찾지 못하면 알고리즘 품질을 수학적으로 보장할 수 없음
- **P1 대응**: 선형계획 완화(Linear Programming Relaxation, LP relaxation), dual fitting, primal-dual, known reduction을 활용해 증명 기준을 확보함 (확인: 근사비 증명 완결성)
- **P2 보장과 실성능 괴리**: 최악 근사비는 보수적이어서 실제 데이터의 성능 또는 서비스 품질을 충분히 설명하지 못할 수 있음
- **P2 대응**: 최악 근사비와 함께 benchmark gap, 평균 성능, 도메인 제약 충족률을 같이 평가함 (확인: OPT gap, 서비스 수준 협약(Service Level Agreement, SLA))
- **P3 대규모 운영 비용**: 다항 시간이라도 `O(n^3)` 이상이면 대규모 실시간 문제에서는 지연이 커질 수 있음
- **P3 대응**: 스트리밍, 병렬화, 샘플링, 온라인 알고리즘으로 계산량을 낮춤 (확인: p95 실행 시간, 메모리)

> 요약: 근사 알고리즘은 수학적 보장을 유지하되 실제 데이터와 운영 시간 기준으로 추가 검증해야 함

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 시설 입지·집합 커버 | 모든 수요를 덮어야 하지만 최적 조합 탐색이 큰 경우 greedy 또는 LP rounding을 적용하고 근사비를 품질 보장으로 제시함 | coverage ratio, 근사비, 비용 초과율 |
| 배송·방문 경로 | 외판원 문제(Traveling Salesman Problem, TSP) 변형은 시간 제한 안에 근사 경로를 산출하고 실제 교통 제약은 후처리 검증으로 분리함 | OPT gap, route violation count, 재계산 시간 |
| 클라우드 자원 배치 | 대규모 bin packing·스케줄링은 근사 알고리즘으로 초기 배치를 만들고 온라인 조정으로 서비스 수준 협약(Service Level Agreement, SLA)을 맞춤 | 자원 사용률, SLA 위반률, p95 배치 시간 |

> 요약: 근사 알고리즘 적용은 근사비 보장, 실제 데이터 gap, 운영 시간 제한을 함께 검증하는 최적화 선택임

## Ⅶ. 전망

- **발전 방향**: GNN, 강화학습, 대규모 solver와 결합해 이론 보장 근사와 데이터 기반 휴리스틱이 함께 발전할 전망임
- **기술사적 판단**: 업무에서 정확해가 불가능하면 근사비, 실행 시간, 위반 비용을 합의해 의사결정 품질을 설계해야 함
- **기술사 제언**: 답안에서는 휴리스틱과 근사 알고리즘의 차이를 근사비 보장 여부로 명확히 구분해야 함
