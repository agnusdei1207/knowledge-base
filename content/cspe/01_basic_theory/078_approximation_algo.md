## 미리 알고가기

- 최적해: 목적 함수를 최적으로 만드는 해임
- 근사해: 최적해는 아니지만 허용 가능한 품질을 가진 해임
- 근사비: 알고리즘 해가 최적해와 얼마나 떨어질 수 있는지 나타내는 보장값임
- 휴리스틱: 경험 규칙으로 빠른 해를 찾지만 품질 보장이 약한 방법임
- 완화(Relaxation): 어려운 제약을 풀어 계산하기 쉬운 문제로 바꾸는 방법임

## Ⅰ. 개요

- **정의/개념**: 근사 알고리즘은 NP-난해 최적화 문제에서 다항 시간 내에 품질 보장이 있는 해를 찾는 알고리즘임
- **배경/필요성**: 제한 시간 안에 쓸 수 있는 해를 구하기 위해 해의 품질을 보장하는 근사 알고리즘이 필요함

## Ⅱ. 특징

- 최적해는 보장하지 않지만 최악 품질 경계를 수학적으로 제시함
- 정확 알고리즘보다 빠르고 휴리스틱보다 설명 가능성이 높음
- 탐욕, LP 완화, 라운딩, 지역 탐색을 문제 구조에 맞게 사용함
- 근사비가 좋아도 상수 비용과 구현 복잡도가 커지는 위험이 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 정확 알고리즘 | 근사 알고리즘 | 휴리스틱 |
|:---|:---|:---|:---|
| 해 품질 | 최적해 보장 | 근사비 보장 | 보장이 약함 |
| 실행 시간 | 지수 시간 가능 | 다항 시간 목표 | 대체로 빠름 |
| 설명 가능성 | 높음 | 높음 | 낮거나 경험 의존 |
| 적합 조건 | 작은 입력, 고정밀 필요 | 큰 입력, 품질 보장 필요 | 실시간, 경험 규칙 충분 |

> 요약: 정확해가 너무 느리고 휴리스틱 보장이 부족할 때 근사 알고리즘을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 목적 함수 | 최소화 또는 최대화할 비용·효용 기준임 |
| 제약 조건 | 해가 만족해야 하는 자원·용량·순서 제한임 |
| 근사비 $\rho$ | 최악 입력에서도 보장되는 해 품질 한계임 |
| 완화 해 | 어려운 정수 제약을 풀어 얻은 중간 해임 |
| 라운딩 규칙 | 완화 해를 실제 가능한 해로 바꾸는 기준임 |

```text
[ 근사 알고리즘 구조 ]
Problem -> Relaxation/Greedy -> Candidate -> Ratio Proof -> Deploy
```

> 요약: 근사 알고리즘은 빠른 후보 해와 근사비 증명을 함께 제공해야 휴리스틱과 구분됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문제 수식화 | --> | 빠른 해 산출 | --> | 품질 증명 | --> | 운영 검증 |
+----------+     +----------+     +----------+     +----------+
```

1. **문제 수식화**: 목적 함수와 제약을 명확히 정의함
2. **빠른 해 산출**: 탐욕, 완화, 라운딩으로 후보 해를 구함
3. **품질 증명**: 후보 해와 최적해의 최악 비율을 계산함
4. **운영 검증**: 실제 데이터에서 해 품질과 계산 시간을 확인함

> 요약: 이론적 근사비는 운영 데이터의 계산 시간과 제약 위반률로 다시 검증해야 함.

## Ⅵ. 실무 적용 및 유의점

1. 물류 배차는 근사비만 보지 말고 실제 제약 위반률·계산 시간·비용 절감률로 검증함
2. 실시간 시스템은 이론적 품질이 좋아도 LP 풀이가 무거우면 탐욕 근사와 지역 탐색을 조합함

## Ⅶ. 결론

- 근사 알고리즘은 정확성 한계와 시간 제약 사이에서 증명 가능한 품질 기준으로 해를 선택하는 방법임

## 작성 근거(검토용)

- 개요는 NP-난해, 다항 시간, 품질 보장을 함께 제시해 근사 알고리즘의 존재 이유를 정의함
- 특징은 최악 경계, 정확/휴리스틱 대비, 대표 기법, 구현 비용을 선택 판단 기준으로 선정함
- Ⅲ은 정확 알고리즘·휴리스틱과 비교해 근사 알고리즘의 중간 위치를 명확히 함
- 구조 도식은 완화·탐욕에서 후보 해와 증명으로 이어지는 절차를 중심으로 배치함
- 유의점은 근사비와 실제 운영 지표가 다를 수 있으므로 계산 시간과 제약 위반률을 포함함
