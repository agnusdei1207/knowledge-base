# 근사 알고리즘 (Approximation Algorithm)

## Ⅰ. 개요

- **정의/개념**: 근사 알고리즘은 최적해를 정확히 구하기 어려운 최적화 문제에서 다항 시간 안에 최적해에 가까운 해를 보장된 품질 범위로 구하는 알고리즘이다.
- **배경/필요성**: NP-hard 문제는 큰 입력에서 정확해 탐색이 비현실적일 수 있으므로, 실행 시간과 해 품질 사이의 균형을 명시적으로 선택해야 한다.

근사 알고리즘의 핵심은 휴리스틱처럼 "대체로 좋다"가 아니라 근사비로 품질 보장을 제공한다는 점이다.

## Ⅱ. 특징 및 비교

| 구분 | 정확 알고리즘 | 근사 알고리즘 | 휴리스틱 |
|---|---|---|---|
| 해 품질 | 최적 보장 | 근사비 보장 | 보장 없을 수 있음 |
| 실행 시간 | 클 수 있음 | 보통 다항 시간 | 빠를 수 있음 |
| 적용 대상 | 작은 입력·특수 구조 | NP-hard 최적화 | 실무 경험 기반 |
| 평가 | 최적성 | approximation ratio | 실험 성능 |

선택 기준은 최적성 요구, 허용 품질 gap, 입력 규모, 시간 제약, 근사비 존재 여부이다.

## Ⅲ. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Optimization Problem | 최소화·최대화 대상 | 목적 함수 |
| Feasible Solution | 제약을 만족하는 해 | 유효성 |
| Approximation Ratio | 최적해 대비 보장 비율 | 품질 보장 |
| Polynomial Time | 실행 시간 조건 | 실용성 |
| Proof | 근사비 증명 | 휴리스틱과 차이 |

```text
문제정의 -> 빠른 해 구성 -> 근사비 증명 -> 실무 품질 검증
```

근사비 증명이 있어야 단순한 빠른 알고리즘이 아니라 예측 가능한 대안이 된다.

## Ⅳ. 문제점 및 개선방안

1. **휴리스틱과 혼동**
   - 품질 보장 없이 경험적으로 좋은 방법을 근사 알고리즘으로 부르면 의미가 흐려진다.
   - **개선방안**: approximation ratio와 증명 여부를 명시한다.

2. **최악 보장과 평균 성능 차이**
   - 근사비는 최악 보장이고 실제 데이터 성능은 다를 수 있다.
   - **개선방안**: 이론 보장과 벤치마크 성능을 함께 제시한다.

3. **제약 조건 누락**
   - 해가 빠르게 나오더라도 업무 제약을 만족하지 않으면 사용할 수 없다.
   - **개선방안**: feasibility check와 constraint repair를 포함한다.

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 물류 경로 | TSP 근사·메타휴리스틱으로 경로 생성 | 비용 gap, 시간 |
| 시설 배치 | set cover 근사 알고리즘 적용 | 커버율, 비용 |
| 스케줄링 | 최적성보다 SLA 내 품질 보장 우선 | 지연, 품질 gap |

## Ⅵ. 결론

근사 알고리즘은 정확해가 비현실적인 문제에서 시간과 품질을 균형 있게 선택하는 방법이다. 근사비 보장, 실행 시간, 제약 만족성을 함께 설명해야 휴리스틱과 구분되는 기술적 의미가 분명해진다.
