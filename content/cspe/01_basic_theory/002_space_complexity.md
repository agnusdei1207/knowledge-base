## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 알고리즘 실행에 필요한 메모리 사용량이 입력 크기 `n`에 따라 증가하는 비율을 점근적으로 분석하는 기법임 |
| **배경/필요성** | 임베디드·모바일 등 메모리 제약 환경에서 알고리즘의 메모리 효율성이 시스템 실현 가능성을 결정함 |
| **출제 의도** | 시간-공간 트레이드오프와 In-place 알고리즘의 의미를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 고정공간  | --> | 가변공간  | --> | 총공간   |
| (상수)   |     | (입력의존)|     | S(n)     |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 고정 공간 | 입력 크기와 무관한 코드·상수·단순 변수 영역임 | 주방 고정 설비 면적 |
| 가변 공간 | 입력 크기에 비례하여 동적 할당되는 배열·재귀 스택 영역임 | 재료 보관 냉장고 크기 |
| 보조 공간(Auxiliary) | 입력 자체를 제외하고 알고리즘이 추가로 사용하는 메모리임 | 조리 시 별도 그릇 |

> 요약: 총 공간 = 고정 공간 + 가변 공간이며, 보조 공간이 O(1)이면 In-place 알고리즘임.

## Ⅲ. 절차
```
+------------+     +------------+
| 변수·배열  | --> | 재귀깊이   |
| 메모리산정  |     | 스택산정   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| O(S(n))   | <-- | 합산후    |
| 표기       |     | 최고차항   |
+------------+     +------------+
```

1. 변수·배열 산정: 알고리즘 내 선언된 배열·리스트·해시맵의 크기를 n의 함수로 계산함
2. 재귀 스택 산정: 재귀 호출 깊이 × 프레임당 메모리를 계산함(예: 병합정렬 O(log n))
3. 합산: 고정 공간 + 가변 공간 + 재귀 스택을 합산하여 총 공간 함수 S(n)을 도출함
4. 점근 표기: 최고차항 추출·계수 제거 후 O(S(n))으로 표기함

> 요약: 변수·배열 + 재귀 스택을 합산하여 최고차항으로 공간 복잡도를 결정함.

## Ⅳ. 문제점
- 시간-공간 트레이드오프: 공간을 줄이면 연산이 증가하고, 연산을 줄이면 캐시·메모리 사용이 증가함
- 숨겨진 메모리: 언어 런타임(GC 오버헤드·객체 헤더)이 분석에서 누락됨
- 재귀 스택 간과: 꼬리 재귀 미최적화 시 O(n) 스택이 발생하여 스택 오버플로우로 이어짐

## Ⅴ. 개선방안
- (단기) In-place 변환: 별도 배열 대신 입력 배열 내에서 교환하여 보조 공간을 O(1)로 줄임
- (중기) 반복문 전환: 재귀를 반복문으로 변환하여 스택 오버헤드를 제거함
- (장기) 스트리밍 알고리즘: 전체 데이터를 메모리에 적재하지 않고 스트림 처리하여 O(1)~O(log n)으로 공간을 절감함

## Ⅵ. 전망
- 엣지·IoT 디바이스의 메모리 제약과 대규모 데이터 처리 수요가 동시에 증가하며, 공간-정확도 트레이드오프를 최적화하는 확률적 자료구조(Bloom Filter·Count-Min Sketch)의 활용이 확대될 전망임
