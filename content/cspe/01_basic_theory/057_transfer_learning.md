# 📖 【암기용】 개념 완전 이해

> 목적: 전이 학습을 처음 보는 사람도 사전학습 모델을 새 업무에 재사용하는 원리를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 큰 데이터로 배운 표현을 작은 데이터 업무에 옮겨 쓰는 학습 방법
- **왜 필요한가**: 실무 데이터는 라벨 수가 부족하고 학습 비용이 큼. 전이 학습은 ImageNet, BERT 같은 사전학습 표현을 재사용해 학습 시간과 라벨 요구량을 줄임.
- **핵심 직관**: 한 번 배운 시각·언어의 기본 패턴을 새 문제의 마지막 판단층에 맞게 조정하는 방식임.

## 깊이 이해
- **배경·문제의식**: 딥러닝은 데이터와 GPU 비용에 민감함. 모든 업무를 처음부터 학습하면 라벨 수만~수백만 건이 필요하므로, 공통 표현을 재사용하는 접근이 필요함.
- **작동 원리**: 사전학습 모델의 하위 계층은 일반 특징을 유지하고, 상위 계층 또는 분류 헤드만 새 데이터로 학습함. 데이터가 충분하면 일부 블록을 풀어 Fine-tuning함.
- **비유**: 의사가 일반 의학을 먼저 배우고, 이후 영상의학·피부과처럼 세부 전공에 맞춰 임상 사례를 추가 학습하는 구조임.
- **구체 예시**: ResNet-50 ImageNet 사전학습 가중치를 사용하고 마지막 FC 계층을 1000클래스에서 5클래스로 교체한 뒤 5,000장 데이터로 Fine-tuning함.
- **흔한 오해·주의점**: 도메인이 다르면 전이가 항상 유리하지 않음. 자연 이미지 모델을 CT 영상에 적용할 때는 도메인 거리, 층별 Freeze 범위, 검증셋 성능을 확인해야 함.

## 연결 개념
- Fine-tuning — 사전학습 모델 일부 또는 전체를 새 데이터로 재학습
- Feature Extraction — 백본은 고정하고 특징 벡터만 추출
- Domain Adaptation — 원천 도메인과 목표 도메인 차이를 줄이는 학습

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 전이 학습은 원천 도메인에서 학습한 표현을 목표 도메인 모델의 초기값·특징추출기로 재사용하는 방법임.
> 2. **가치**: 라벨 1천~1만 건 규모에서도 사전학습 백본을 활용해 학습 시간과 과적합 위험을 낮춤.
> 3. **판단 포인트**: 데이터 규모, 도메인 유사도, Freeze 범위, Negative Transfer 여부를 함께 판단해야 함.

---

## Ⅰ. 개요 및 필요성

전이 학습은 학습된 지식을 새 문제에 재사용한다. AI 프로젝트는 라벨 수집, GPU 학습, 검증 비용이 병목이므로 사전학습 모델 활용이 기본 전략이 됨. 목표 도메인 데이터가 적을수록 Feature Extraction과 단계적 Fine-tuning 판단이 중요함.

---

## Ⅱ. 구조 및 구성요소

```text
Source Data -> Pretrained Backbone -> Feature Layer -> Task Head -> Target Output
Target Data ------------------------> Fine-tuning / Freeze Control -> Evaluation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Source Model | 대규모 원천 데이터로 학습된 백본 | ImageNet, BERT, CLIP |
| Feature Layer | 일반 패턴을 벡터로 표현 | 엣지·문법·의미 특징 |
| Task Head | 목표 업무 분류·회귀 출력 | 클래스 수에 맞춰 교체 |
| Fine-tuning Policy | Freeze·Unfreeze 범위 결정 | 데이터 1만 건 미만이면 보수적 해제 |

> 요약: 전이 학습은 사전학습 백본, 특징 계층, 업무 헤드, 미세조정 정책으로 목표 업무를 구성함.

---

## Ⅲ. 동작원리 및 흐름도

```text
사전학습 모델 선택 -> 목표 데이터 전처리 -> 헤드 교체
-> 백본 Freeze -> 헤드 학습 -> 일부 계층 Unfreeze
-> 검증셋 평가 -> 배포 후보 선정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원천 모델과 목표 도메인 유사도 확인 | 데이터 형태, 클래스 의미 |
| 2 | 마지막 계층을 목표 클래스 수로 교체 | 출력 차원 일치 |
| 3 | Freeze 후 헤드 우선 학습 | Train/Val Gap 5%p 이하 |
| 4 | 상위 블록 Fine-tuning 및 평가 | Accuracy, F1, AUC |

> 요약: 전이 학습은 헤드 학습 후 일부 계층 해제 순서로 과적합과 Negative Transfer를 점검함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 라벨 부족 환경에서 초기 표현 재사용 | 라벨 1천~1만 건 구간 |
| 한계 | 원천·목표 도메인 차이로 성능 하락 | Negative Transfer, 검증 F1 감소 |
| 비교 대상 | Scratch 학습은 데이터와 GPU 요구량 큼 | 10만 건 이상이면 Scratch 병행 검토 |

> 요약: 전이 학습은 소량 라벨 업무에 적합하나 도메인 차이가 크면 검증셋 기준으로 중단해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | Scratch는 전체 가중치 무작위 초기화 | 사전학습 백본 재사용 | 라벨 1만 건 미만이면 전이 학습 |
| 비용/성능 | GPU 학습 수십~수백 epoch | 헤드 학습 5~20 epoch | 학습 시간 50% 이상 절감 목표 |
| 운영/위험 | 업무별 모델 분산 | 공통 백본 표준화 | 모델 버전·라이선스 관리 |

> 요약: 데이터가 적고 원천 도메인과 유사하면 전이 학습, 데이터가 충분하고 도메인이 특수하면 Scratch를 병행함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Negative Transfer | 원천·목표 분포 차이 | 도메인 유사도 분석, 상위층만 학습 | Val F1 기준선 대비 |
| 과적합 | 목표 데이터 부족 | Freeze, Dropout 0.2~0.5, Early Stopping | Train/Val Gap |
| 라이선스 위험 | 공개 모델 사용 조건 미확인 | 모델 카드·라이선스 검토 | 승인 기록, SBOM |

> 요약: 전이 학습 리스크는 도메인 차이, 과적합, 라이선스 검토로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 예측 품질 | F1 0.85 이상 또는 기준선 대비 5%p 이상 | Hold-out, K-Fold |
| 학습 비용 | Scratch 대비 GPU 시간 50% 이상 절감 | MLflow, 학습 로그 |
| 운영/보안 | 모델 카드·라이선스 100% 등록 | 모델 레지스트리 점검 |

> 요약: 전이 학습 성공 여부는 검증 F1, GPU 시간, 모델 라이선스 추적성으로 판단함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 모델 선정: ResNet, EfficientNet, BERT, CLIP 중 데이터 형태와 라이선스가 맞는 백본을 모델 카드 기준으로 선택.
2. 학습 전략: 1단계 헤드만 10 epoch 학습, 2단계 상위 블록 Unfreeze, Learning Rate 1e-5~1e-4 적용.
3. 운영 관리: MLflow로 모델 버전·데이터셋 해시·F1·AUC 기록, 기준선 대비 5%p 미만이면 배포 보류.

**결론 (2줄):**
- 기술사 판단: 목표 데이터가 1만 건 미만이고 도메인 유사도가 높으면 전이 학습, 특수 센서·전용 분포이면 Scratch 병행 검증이 필요함.
- 향후 방향: 전이 학습은 Foundation Model, Adapter, LoRA 기반 파라미터 절감 Fine-tuning으로 확장됨.
