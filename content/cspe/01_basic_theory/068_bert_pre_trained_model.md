# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: BERT는 **사전학습 언어 모델**(Pre-trained Language Model)의 한 갈래로, 트랜스포머(Transformer)의 **인코더**(Encoder)만 층층이 쌓아 문장 전체를 **양방향**으로 동시에 읽어 문맥을 이해하는 모델이다.
- **왜 필요한가**: 기존 단방향 모델(RNN·LSTM)은 왼쪽에서 오른쪽으로만 문장을 읽어, "그는 배가 아파 [ ]를 먹었다"에서 [ ]를 채울 때 뒤에 나올 단어("약")의 정보를 전혀 쓰지 못했다. 다의어·문맥 의존 표현을 정확히 풀려면 앞뒤를 동시에 봐야 한다.
- **핵심 직관**: 문장 토큰의 15%를 가리고 주변 단어로 맞히는 "빈칸 채우기"(MLM)를 대규모 코퍼스에서 수억 번 반복시켜, 사람이 만든 정답 라벨 없이(자기지도학습) 언어 자체의 문맥 규칙을 스스로 익히게 한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 사전학습 언어 모델 | 라벨 없는 대량 텍스트로 먼저 언어 자체를 학습하고, 실제 작업(분류 등)은 나중에 소량 데이터로 맞추는 모델 — BERT가 속하는 **상위 범주** | 외국어를 다독으로 익힌 뒤, 시험 유형만 나중에 몇 번 풀어보고 적응 |
| 트랜스포머(Transformer) | Self-Attention만으로 문장 내 모든 단어 간 관계를 한 번에 계산하는 신경망 구조 — BERT의 **뼈대** | 반 전체 학생이 동시에 서로를 쳐다보며 관계를 파악하는 자리 |
| 인코더(Encoder) | 트랜스포머 중 입력을 "이해"만 담당하는 절반 — BERT는 이것만 사용(디코더는 GPT가 사용) | 원문을 읽고 요약 노트만 만드는 역할(문장을 새로 짓지는 않음) |
| Self-Attention(Q·K·V) | 각 단어의 질의(Query)와 문장 내 모든 단어의 열쇠(Key)를 비교해 관련도를 구하고, 그 가중치로 값(Value)을 합산하는 연산 | 회의에서 내 발언(Query)이 누구의 발언(Key)과 관련 있는지 따져 그 사람 의견(Value)을 더 반영 |
| 양방향 문맥(Bidirectional) | 왼쪽·오른쪽 단어를 동시에 참조해 의미를 파악하는 방식 | 앞뒤 문장을 다 읽고 나서 빈칸 단어를 추측 |
| MLM(Masked Language Model) | 입력 토큰 일부를 가리고 주변 문맥으로 원래 단어를 맞히게 하는 사전학습 과제 | 지문에 뚫린 빈칸을 앞뒤 문맥으로 채우는 시험 |
| NSP(Next Sentence Prediction) | 두 문장이 실제로 이어지는 문장인지 판별하는 이진 분류 사전학습 과제 | 두 문단을 주고 "원래 순서로 이어지는 글이 맞나?"를 맞히는 퀴즈 |
| WordPiece | 단어를 더 잘게 쪼갠 서브워드 단위 토큰화 방식 — 사전에 없는 단어도 조각으로 표현 | "unhappiness"를 "un"+"happi"+"ness"로 쪼개 모르는 단어를 없앰 |
| [CLS] / [SEP] | 문장 맨 앞에 붙여 전체 의미를 압축하는 토큰([CLS]) / 문장 경계를 표시하는 구분 토큰([SEP]) | [CLS]는 답안지 맨 위 "총평 칸", [SEP]는 문단 사이 구분선 |
| 파인튜닝(Fine-tuning) | 사전학습된 가중치는 거의 그대로 두고, 특정 작업에 맞춰 소량 데이터로 미세 조정하는 단계 | 언어를 다독으로 익힌 사람에게 특정 시험 문제 유형만 몇 십 문제 풀려 적응시킴 |

## 깊이 이해

### 왜 인코더만 떼어냈나 (배경)
- 2017년 발표된 트랜스포머는 원래 번역기용으로 인코더(원문 이해)+디코더(번역문 생성) 쌍으로 설계됐다.
- 구글 연구진은 "번역처럼 새 문장을 만들 필요 없이, 문장을 정확히 '이해'만 하면 되는 작업(분류·질의응답·개체명 인식)이 훨씬 많다"는 점에 착안해 2018년 인코더만 떼어내 크게 쌓아 BERT를 만들었다. 디코더가 없으므로 BERT는 문장을 순차적으로 "생성"하지 못하고, 대신 입력 전체를 한 번에 훑어 문맥 표현을 뽑아내는 데 특화된다.

### Self-Attention을 수치로 이해하기
- 각 단어 벡터에서 Query·Key·Value 세 벡터를 만든 뒤, 한 단어의 Query와 문장 내 모든 단어의 Key를 내적(dot product)해 유사도 점수를 구하고, 소프트맥스로 정규화한 가중치로 Value를 가중합한다. 수식: Attention(Q,K,V) = softmax(QKᵀ/√d_k)·V.
- 예: "그 동물은 강을 건너지 못했다. 왜냐하면 그것이 너무 지쳤기 때문이다"에서 "그것"의 Query는 "동물"의 Key와 내적값이 가장 커서(예: 정규화 후 가중치 0.7, 나머지 단어는 0.05~0.1 수준으로 분산) "그것 = 동물"이라는 관계를 학습한다.
- 이 연산은 토큰 n개짜리 문장에서 모든 토큰 쌍의 관계를 계산하므로 연산량이 O(n²)이다. 문장 길이가 512 토큰이면 512×512=262,144개 쌍을 계산해야 한다 — 이것이 BERT가 긴 문서를 통째로 넣기 어려운 이유다.

### MLM 마스킹 규칙을 수치로 이해하기
- 입력 토큰의 15%를 마스킹 후보로 뽑는다. 그중 80%는 진짜 `[MASK]` 토큰으로, 10%는 엉뚱한 무작위 단어로, 10%는 원래 단어 그대로 둔다.
- 예: 문장이 100개 토큰이면 15개가 후보가 되고, 그중 약 12개는 `[MASK]`로, 1~2개는 무작위 단어로, 1~2개는 원래 그대로 남는다.
- 100% `[MASK]`로 통일하지 않는 이유: 실제 사용(파인튜닝·추론) 시에는 `[MASK]` 토큰이 등장하지 않는다. 학습 때만 보던 토큰이 실전에 없으면 성능이 어긋나므로, 일부를 무작위·원본으로 섞어 모델이 "이 자리가 마스킹된 자리인지" 구분 없이 항상 문맥을 예측하도록 강제한다.

### NSP를 수치로 이해하기
- 학습 데이터의 50%는 코퍼스에서 실제로 이어지는 두 문장(IsNext), 나머지 50%는 서로 관련 없는 문장을 무작위로 짝지은 것(NotNext)이다.
- `[CLS]` 토큰의 최종 출력 벡터 하나로 이 이진 분류를 수행한다. 이 과제 덕분에 BERT는 단어 수준 문맥뿐 아니라 문장 간 관계(질의응답, 문단 순서 판별 등)도 사전학습 단계에서 함께 익힌다.

### 모델 규모를 수치로 이해하기
- BERT-Base: 인코더 층 12개, 은닉 차원 768, 어텐션 헤드 12개, 파라미터 약 1억 1천만 개(110M).
- BERT-Large: 인코더 층 24개, 은닉 차원 1024, 어텐션 헤드 16개, 파라미터 약 3억 4천만 개(340M).
- 학습 데이터는 BooksCorpus(약 8억 단어) + 영어 위키백과(약 25억 단어)로, 총 30억 단어 규모의 텍스트를 라벨 없이 학습한다.

### 비유와 흔한 오해
- 비유: 외국어 지문에서 군데군데 뚫린 빈칸을 앞뒤 문맥으로 추론해 채우는 시험을 수억 번 반복하며 언어 감각을 익힌 학생과 같다. 이 학생은 이미 익힌 감각(가중치)을 그대로 유지한 채, 나중에 특정 시험(분류·QA)만 몇 문제 더 풀며 적응(파인튜닝)한다.
- 오해 1: BERT는 챗봇처럼 다음 단어를 순차 생성하지 못한다. 디코더가 없어 "생성"이 아니라 "이해"에만 최적화돼 있다.
- 오해 2: 파인튜닝은 모델을 처음부터 다시 학습하는 게 아니다. 사전학습된 수억 개 가중치는 거의 그대로 두고, 출력층 근처만 소량 데이터(수천~수만 건)로 미세 조정한다.

## 연결 개념
- 트랜스포머(Transformer) — Self-Attention 기반 구조. BERT는 이 중 인코더만 사용한다.
- GPT(Generative Pre-trained Transformer, 069) — 같은 트랜스포머에서 디코더만 사용해 생성에 특화된 모델. Self-Attention 수식은 같고, "미래 토큰을 가리는지" 여부만 다르다.
- 워드 임베딩(Word2Vec 등, 067) — 같은 단어면 문맥과 무관하게 벡터가 고정되는 정적 임베딩. BERT는 같은 단어라도 문맥마다 벡터가 달라지는 동적 임베딩이라는 점에서 대비된다.
- 파인튜닝(Fine-Tuning) — 사전학습된 BERT를 특정 작업(분류, 번역)에 맞게 미세 조정하는 과정

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 트랜스포머 인코더 기반의 양방향성(Bidirectional)과 MLM/NSP 사전학습 방식, 그리고 NLU 영역에서의 미세조정(Fine-tuning) 가치를 설명한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: BERT는 양방향 트랜스포머 인코더를 활용하여 문맥을 깊이 있게 인코딩하는 사전학습(Pre-training) 언어 모델이다.
> 2. **가치**: 대규모 무상태(Self-supervised) 코퍼스로 언어 이해(NLU) 능력을 사전학습한 후, 소량의 라벨 데이터로 파인 튜닝하여 SOTA 성능을 달성한다.
> 3. **판단 포인트**: 생성(NLG) 태스크에는 GPT 계열을, 분류·추출·질의응답 등 이해(NLU) 태스크에는 BERT 계열을 선택하는 아키텍처 판단이 중요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 트랜스포머 아키텍처 응용 역량 확인 | Transformer Encoder, Bidirectional, Self-Attention | 트랜스포머 전체(인코더+디코더)로 설명하면 오답 |
| 사전학습 방법론 이해 검증 | MLM (Masked LM), NSP (Next Sentence Prediction) | 단방향(Autoregressive) 생성 모델 방식과 혼동 |
| 태스크별 모델 선택 기준 제시 | 파인 튜닝(Fine-tuning), NLU(자연어 이해) 최적화 | 생성 작업(챗봇 대화 생성)에 BERT를 추천 |

> 요약: 인코더 중심의 양방향 구조와 MLM/NSP 사전학습 방식을 명시하고, NLU 영역 파인튜닝의 실무적 가치를 강조한다.

## Ⅰ. 개요 및 필요성

- 정의: 양방향 트랜스포머 인코더 기반으로 심층 문맥을 모델링하는 사전학습 자연어 처리 모델
- 배경: 단방향(Left-to-Right) 언어 모델은 뒤에 나오는 단어 정보를 앞 단어 추론에 활용할 수 없는 구조적 한계 내재
- 필요성: 고비용 라벨링 데이터 의존성을 낮추기 위해, 대규모 위키백과 데이터 등에서 자가지도학습(Self-supervised) 사전학습 수행 필수

---

## Ⅱ. 구조 및 구성요소

```text
Input (Token+Segment+Position) -> Transformer Encoder Stack -> Hidden States
                                     |
                                     +-> MLM Head (단어 예측) / NSP Head (문장 관계)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Transformer Encoder | Self-Attention으로 입력 시퀀스 전체의 양방향 문맥 반영 | `[CLS]` 토큰으로 전체 문장 의미 압축 |
| 임베딩 (Embedding) | Token, Segment(문장 구분), Position(위치) 임베딩 합산 | 위치 정보를 상대적/절대적으로 주입 |
| MLM (Masked LM) | 입력 토큰의 15%를 `[MASK]`로 치환 후 원본 토큰 예측 학습 | 양방향 문맥 동시 참조 가능 |
| NSP (Next Sentence Prediction) | 두 문장이 연속된 문장인지(IsNext/NotNext) 이진 분류 | 질의응답(QA), 자연어 추론(NLI) 성능 향상 |

> 요약: BERT 구조는 다중 임베딩 입력과 트랜스포머 인코더 스택으로 구성되며, MLM과 NSP라는 두 가지 사전학습 목표로 훈련된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
대규모 코퍼스 수집 -> 사전학습(Pre-training, MLM/NSP) -> 파인튜닝(Fine-Tuning) -> 작업별 추론(Inference)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 코퍼스 구축 | 위키피디아 25억 단어, BookCorpus 8억 단어 수집 |
| 2 | 토큰화 | WordPiece BPE 알고리즘 적용 (OOV 문제 완화) |
| 3 | 사전학습 (Pre-training) | 15% 토큰 마스킹 및 문장 간 연속성 분류 손실함수 최소화 |
| 4 | 파인 튜닝 (Fine-Tuning) | 개체명 인식(NER), 감성 분석 등 타겟 태스크 레이블로 가중치 갱신 |

> 요약: 범용 코퍼스 기반 자가지도 사전학습(Pre-training)을 완료한 후, 특정 작업용 라벨 데이터로 전체 가중치를 미세조정(Fine-Tuning)하여 적용한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 양방향 인코딩 | 문장의 앞뒤 맥락을 동시에 참조하여 어휘의 다의어 분별 | Word2Vec(고정 벡터) 대비 문맥 의존적 임베딩 |
| 미세조정 용이성 | 사전학습 모델 최상단에 1개의 Dense Layer만 추가하여 태스크 수행 | 태스크별 복잡한 네트워크 재설계 불필요 |
| 한계 | 추론 시 전체 입력 시퀀스를 한 번에 연산하므로 지연시간 발생 | 실시간 생성(NLG) 태스크에는 부적합 |

> 요약: 사전학습을 통한 강력한 양방향 문맥 이해력(NLU)을 제공하나, 무거운 인코더 구조로 인해 추론 지연과 생성 부적합 한계가 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Word2Vec / GloVe | BERT (Transformer Encoder) | GPT (Transformer Decoder) |
|:---|:---|:---|:---|
| 문맥 반영 | 정적(고정) 임베딩 | 동적(양방향) 임베딩 | 동적(단방향 Autoregressive) |
| 주 활용 분야 | 단어 간 유사도 계산 | 분류, 추출, QA (NLU) | 문장 생성, 대화 모델 (NLG) |
| 학습 패러다임 | 주변 단어로 타겟 예측 | MLM(마스크 예측), NSP | 다음 단어 예측(Next Token) |

> 요약: 태스크가 감성 분석이나 개체명 추출이면 BERT를, 요약이나 자유 대화 생성이라면 단방향의 GPT 구조를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 메모리/지연시간 초과 | 트랜스포머의 $O(n^2)$ 연산 복잡도 | ALBERT(파라미터 공유), DistilBERT 도입 | 파라미터 수, p95 Inference Latency |
| 도메인 어휘 인식 실패 | 범용 코퍼스(위키) 위주의 사전학습 | 도메인 특화 코퍼스로 추가 사전학습 | 도메인 테스트셋 분류 정확도 |

> 요약: BERT의 $O(n^2)$ 연산 비용과 도메인 한계는 경량화 모델(DistilBERT) 도입 및 도메인 특화 사전학습으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 분류/추출 정확도 | 태스크별 F1-score, EM(Exact Match) 목표치 이상 | GLUE/KLUE 등 벤치마크 검증 |
| 추론 지연시간 | p95 Inference Latency 실시간 서비스 SLA 이내 | 추론 서버 부하 테스트 |
| 도메인 적합도 | 도메인 특화 코퍼스 추가 학습 후 정확도 개선폭 | 도메인 테스트셋 Before/After 비교 |

> 요약: BERT 적용 효과는 태스크 정확도, 추론 지연시간, 도메인 적합도 개선폭을 함께 확인해야 검증된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 고객 감성 분석: 콜센터 상담 텍스트 10만 건에 Fine-tuning하여 긍정/부정 분류 및 주요 불만 개체명 추출 정확도 92% 달성
2. 엔터프라이즈 검색(RAG): 사내 규정 문서 5만 건을 BERT 파생 모델(SBERT)로 벡터 임베딩하여 시맨틱 검색 엔진 구축
3. 경량화(Edge AI) 적용: 모바일 기기 탑재를 위해 지식 증류를 거친 DistilBERT 적용, 성능 97% 유지하며 파라미터 40% 감축

**결론 (2줄):**
- 기술사 판단: 정밀한 의미 분석(분류/검색)이 목표라면 BERT 계열을 도입하고, 경량화(DistilBERT)를 통해 추론 병목을 통제해야 한다.
- 향후 방향: 최근 LLM 트렌드는 생성형 GPT 모델이 주도하나, 정보 검색과 RAG 아키텍처의 리트리버 단계에서는 여전히 BERT 기반 임베딩 모델이 핵심이다.
