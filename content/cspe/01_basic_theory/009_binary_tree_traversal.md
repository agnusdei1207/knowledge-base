# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 트리의 모든 노드를 중복 없이 한 번씩 빠짐없이 방문하는 일련의 규칙이다.
- **왜 필요한가**: 1차원 배열은 인덱스 0부터 순서대로 읽으면 되지만, 비선형인 트리는 '어디부터 읽을지' 규칙을 정하지 않으면 데이터를 전부 순회할 수 없기 때문이다.
- **핵심 직관**: 부모 노드(루트)를 언제 방문하느냐가 핵심이다. 루트를 가장 먼저 방문하면 전위(Pre), 중간에 방문하면 중위(In), 마지막에 방문하면 후위(Post) 순회다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 순회 (Traversal) | 트리 내부의 모든 데이터를 빠짐없이 한 번씩 확인하는 과정 | 박물관의 모든 전시관을 정해진 동선대로 관람하는 것 |
| 전위 순회 (Pre-order) | 루트 -> 왼쪽 -> 오른쪽 순서로 방문 | 사장님 지시 -> 1팀 -> 2팀 (위에서 아래로 하달) |
| 중위 순회 (In-order) | 왼쪽 -> 루트 -> 오른쪽 순서로 방문 | 왼쪽 잎 -> 줄기 -> 오른쪽 잎 (정렬된 결과) |
| 후위 순회 (Post-order) | 왼쪽 -> 오른쪽 -> 루트 순서로 방문 | 자식들 일 다 끝내고 -> 부모가 최종 승인 |

## 깊이 이해
- **배경·문제의식**: "트리의 모든 데이터를 한 번씩 출력해봐"라고 할 때, 갈림길(자식 노드)이 존재하므로 단순 루프(`for`)로는 불가능하다. 스택 메모리를 활용한 재귀(Recursion) 호출을 기반으로 방문 순서를 통제하는 기법이 필요해졌다.
- **작동 원리 (재귀 기반)**:
  - 순회의 기준은 항상 **"현재 서브 트리의 루트(나 자신)를 언제 출력할 것인가?"**이다.
  - 전위(V-L-R): 나 자신(Visit) 먼저 -> 그 다음 왼쪽 끝까지 파고들기 -> 그 다음 오른쪽.
  - 중위(L-V-R): 왼쪽 끝까지 내려간 뒤 -> 올라오면서 나 자신(Visit) -> 오른쪽. (이진 탐색 트리에서 오름차순 정렬 결과를 얻음)
  - 후위(L-R-V): 양쪽 자식을 다 처리한 뒤 -> 마지막에 나 자신(Visit).
- **비유**: 
  - 전위(Pre): 폴더 복사. 상위 폴더를 먼저 만들고(V) 그 안에 하위 파일들을 복사(L, R)해 넣는다.
  - 후위(Post): 폴더 삭제. 하위 파일(L, R)을 모두 먼저 지워야만 마지막에 상위 폴더(V)를 지울 수 있다.
- **구체 예시**: 수식 `(A + B)`가 트리로 구성되었을 때, `+`가 루트고 A, B가 자식이다. 
  - 전위: `+ A B` (폴리시 표기법)
  - 중위: `A + B` (우리가 쓰는 일반 수식)
  - 후위: `A B +` (스택 계산기가 쓰는 후위 표기법)
- **흔한 오해·주의점**: 순회를 단순한 '출력용'으로만 오해하기 쉽다. 순회는 트리의 복사, 삭제, 수식 평가 등 **트리를 조작하는 작업 순서**를 결정하는 근본적인 아키텍처다.

## 연결 개념
- 스택 (007 참조): 재귀 호출을 지원하여 순회를 가능하게 하는 이면의 핵심 자료구조.
- 완전 이진 트리 (008 참조): 트리의 기본 형태.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진 트리 순회는 비선형 자료구조의 모든 노드를 재귀(스택) 기반으로 체계적이고 중복 없이 방문하는 경로 탐색 기법이다.
> 2. **가치**: 루트 노드의 방문 순서(전/중/후)를 조작함으로써, 폴더 구조 복사/삭제나 수식 계산(컴파일러) 등 시스템 계층 처리의 기반 논리를 제공한다.
> 3. **판단 포인트**: 트리를 어떠한 목적(정렬 조회, 객체 생성, 계층 삭제)으로 다룰 것인지에 따라 순회 방식을 다르게 매핑(Mapping)하는 설계 결단이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 비선형 구조의 탐색(순회) 원리 이해 | 전/중/후위 순회의 L, R, V 방문 순서와 재귀(스택) 원리 | 결과만 적고 내부의 재귀(스택) 동작 메커니즘 누락 |
| 순회 기법별 실무 응용처 매핑 | 전위(복사), 중위(오름차순), 후위(삭제/계산) 목적 매핑 | "단순히 출력 순서만 다름"으로 치부하는 오답 |
| 수식 트리 변환 역량 (응용) | 수식 트리를 전위/후위 표기법으로 변환하는 과정 | 수식 변환 과정의 트리 구성 오류 |

> 요약: 트리 순회는 루트(V)의 방문 시점에 따라 나뉘며, 이는 단순 출력을 넘어 복사, 정렬, 삭제 등 계층적 데이터 조작의 논리적 순서를 결정한다.

## Ⅰ. 개요 및 필요성

- 개요: 이진 트리 순회(Traversal)는 루트(Visit), 왼쪽(Left), 오른쪽(Right) 자식 노드의 방문 순서를 조합하여 비선형 데이터 전체를 중복 없이 탐색하는 기법임
- 배경: 1차원 선형 루프(`for`문)로는 분기가 존재하는 계층적 데이터의 모든 노드를 체계적으로 방문할 수 없는 한계 존재
- 필요성: 디렉터리 복사/삭제, 컴파일러의 수식 구문 분석, 이진 탐색 트리의 정렬된 출력 등 계층 구조 제어를 위해 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
       [Root (V)]
       /        \
 [Left (L)]   [Right (R)]
 
- 전위 (Pre-order) : V -> L -> R
- 중위 (In-order)  : L -> V -> R
- 후위 (Post-order): L -> R -> V
```

| 순회 기법 | 방문 순서 (Visit 기준) | 실무 주요 활용처 |
|:---|:---|:---|
| 전위 순회 (Pre-order) | **V** -> L -> R (루트 먼저) | 트리 전체 복사, XML/JSON 생성, Prefix 수식 |
| 중위 순회 (In-order) | L -> **V** -> R (루트 중간) | 이진 탐색 트리(BST)의 오름차순 정렬 조회 |
| 후위 순회 (Post-order)| L -> R -> **V** (루트 마지막) | 하위부터 삭제하는 디렉터리 삭제, Postfix 수식 계산 |

> 요약: 3가지 순회 기법은 상위 노드의 처리 시점(V)을 결정하며, 각 기법은 트리를 조작(생성, 정렬, 삭제)하는 목적과 정확히 1:1 매핑된다.

## Ⅲ. 동작원리 및 흐름도 (후위 순회 재귀 기준)

```text
탐색 시작(Node) -> [Node Null 여부 검사] -> [False] 종료 / [True] 왼쪽 파고들기
  |
  +-> 왼쪽 재귀 (PostOrder(Node.Left)) 완료 후
  +-> 오른쪽 재귀 (PostOrder(Node.Right)) 완료 후
  +-> 최종 루트 연산 (Visit(Node)) -> 상위 콜 스택으로 복귀
```

- 1단계 [진입 및 검증]: 현재 노드가 Null인지 확인하여 재귀 호출의 탈출 조건(Base Case) 만족 여부 판단
- 2단계 [Left 재귀 하강]: 현재 노드를 스택에 보존(상태 저장)한 채, 왼쪽 자식으로 가장 깊은 단말까지 계속 내려감
- 3단계 [Right 재귀 하강]: 왼쪽 탐색이 끝나면 오른쪽 자식으로 이동하여 하위 서브 트리를 동일하게 탐색
- 4단계 [Visit 수행 및 반환]: 양쪽 자식 탐색(또는 처리)이 모두 끝난 후 마지막에 현재 노드를 처리(출력/삭제 등)하고 상위로 복귀

> 요약: 시스템 스택 메모리를 활용한 재귀(Recursion) 호출을 통해, 하위 트리의 처리가 완료될 때까지 상위 노드의 처리를 지연(Delay)시킨다.

---

## Ⅳ. 특징

- 재귀적 종속성: 모든 순회 로직은 서브 트리에도 동일한 규칙이 반복 적용되는 프랙탈(Fractal) 형태의 재귀 구조를 띰
- 시간 복잡도 O(N): 어떤 순회 방식을 선택하든 전체 N개의 노드를 정확히 한 번씩만 방문하므로 탐색 시간에 차이가 없음
- 공간 오버헤드: 재귀 호출로 인해 시스템 스택 메모리를 트리의 높이(h)만큼 사용하므로, 편향 트리의 경우 O(N)의 스택 공간이 소비됨

> 요약: 속도는 모두 O(N)으로 동일하나, 재귀 호출로 인한 스택 오버플로우(Stack Overflow) 위험을 내포하고 있다.

## Ⅴ. 심화 비교 및 적용 판단 (탐색 기법별 비교)

| 비교 축 | DFS 계열 (전/중/후 순회) | BFS 계열 (레벨 순회) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 / 자료형 | 깊이 파고들기 / Stack (재귀) | 계층(가로) 단위 탐색 / Queue | 목표 데이터의 위치 예상치 |
| 활용 목적 | 전체 노드의 조건부 연산 (복사/삭제) | 최단 경로 탐색, 계층별 직렬화 | 트리 전체 갱신 vs 계층 조회 |
| 메모리 부하 | 최악 O(N) (편향 트리 시 스택 고갈) | 최악 O(N) (가로 폭이 넓은 리프 큐 포화)| 트리의 물리적 형태 (깊이 vs 너비) |

> 요약: 전/중/후위 순회는 깊이 우선(DFS) 철학을 따르며 계층간 관계를 유지할 때 쓰고, 레벨 순회(BFS)는 트리 높이를 최소화한 넓은 탐색에 쓴다.

**리스크·대응 (기본은 불릿):**
- 재귀 깊이 포화(Stack Overflow) 리스크: 대용량 편향 트리 순회 시 OS가 할당한 스택 프레임 한계 초과로 프로세스 강제 종료 -> 재귀를 제거하고 명시적 스택(Explicit Stack) 자료구조를 활용한 반복문(Iteration) 기반 순회로 전환 (지표: 최대 트리 허용 깊이 Max Depth)
- 성능 블로킹 리스크: 순회 중 `Visit()` 연산에 긴 지연 시간(Disk I/O)이 포함되면 전체 트리를 잠금(Lock)하여 시스템 프리징 발생 -> 1회 순회 시 포인터만 수집하고, 비동기 큐에 위임하여 병렬 처리 (지표: 순회 전체 완료 지연 시간)

**도입 후 점검 지표 (기본은 불릿):**
- 성능/효율: 깊이가 10,000 이상인 트리 순회 시 스택 메모리 사용량(MB) — JMX 힙/스택 덤프 분석
- 품질/운영: 중위 순회 결과의 오름차순 정렬 실패율 (BST 밸런싱 오류 검출용 지표)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 구문 분석(Syntax Tree): 소스 코드의 수식을 추상 구문 트리(AST)로 파싱한 후, 후위 순회(Post-order)로 스택 기반 기계어(어셈블리) 코드를 생성하여 피연산자가 연산자보다 먼저 처리되도록 아키텍처 구성
2. GC(Garbage Collection) 마크 단계: JVM의 가비지 컬렉터가 객체 참조 트리를 전위 순회(Pre-order) 방식(DFS)으로 추적하며 활성 객체를 마킹(Mark)하여 메모리 회수 대상 선별
3. 디렉터리 아카이빙(압축/삭제): 대규모 파일 시스템에서 특정 폴더를 완전히 삭제(`rm -rf`)할 때, 하위 파일/폴더를 먼저 지우는 후위 순회 로직을 커널 수준에 적용

**결론 (2줄):**
- 기술사 판단: 트리 순회는 단순한 '읽기 규칙'이 아니라, 재귀(스택)를 이용해 비선형 공간의 복잡도를 선형 시간(O(N)) 제어 흐름으로 풀어내는 컴퓨팅 시스템의 근본 해법임
- 향후 방향: 빅데이터 분산 환경에서는 단일 스레드 순회의 한계를 극복하기 위해, 서브 트리를 쪼개어 멀티 코어에서 병렬(Parallel)로 분할 순회하는 알고리즘 최적화가 요구됨
