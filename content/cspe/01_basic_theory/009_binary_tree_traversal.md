# 이진트리 순회 - 전위·중위·후위 (Binary Tree Traversal)

## 미리 알고가기

- **재귀(recursion)**: 한 노드를 처리할 때 "왼쪽에도 똑같이 해라, 오른쪽에도 똑같이 해라"고 자기 자신을 다시 부르는 방식. 큰 트리를 같은 규칙의 작은 트리로 쪼개 처리한다.
- **콜 스택(call stack)**: 재귀로 잠시 미뤄 둔 "돌아와서 마저 할 일"이 쌓이는 메모리 공간. 내려간 깊이만큼 쌓였다가 되돌아오며 풀린다.

## 1. 개요

- **정의/개념**: 이진트리 순회는 위아래로 뻗은 트리의 모든 노드를 빠짐없이 한 번씩 훑되, "지금 노드 자신을 왼쪽·오른쪽 자식보다 언제 처리하느냐"를 정해 계층 구조를 한 줄로 늘어선 처리 순서로 바꾸는 방법이다.
- **배경/필요성**: 트리는 가지가 갈라져 있어 "다음에 뭘 처리할지"가 배열처럼 자명하지 않은데, 같은 트리라도 루트를 자식보다 먼저 보느냐 나중에 보느냐에 따라 정렬된 출력, 원본 트리 복원, 안전한 삭제, 수식 계산처럼 결과가 완전히 달라지므로, 목적에 맞는 방문 순서를 골라야 한다.

## 2. 특징 및 비교

순회 이름의 "전·중·후"는 곧 **루트를 언제 처리하느냐**를 가리킨다. 왼쪽·오른쪽 자식은 항상 왼쪽 먼저 보고, 그 사이 어디에 루트를 끼우느냐만 다르다.

| 구분 | 방문 순서 | 한마디로 | 대표 활용 |
|:---|:---|:---|:---|
| 전위(Preorder) | 루트 -> 왼쪽 -> 오른쪽 | 나부터 처리하고 아래로 | 트리 복사·직렬화, 전위 표기식 |
| 중위(Inorder) | 왼쪽 -> 루트 -> 오른쪽 | 작은 것부터 순서대로 | 이진 탐색 트리의 정렬 출력 |
| 후위(Postorder) | 왼쪽 -> 오른쪽 -> 루트 | 자식 다 끝내고 나를 처리 | 트리 삭제, 후위 표기식 계산 |
| 레벨(Level) | 가까운 층부터 한 줄씩 | 가로로 층층이 | 너비 우선 탐색(BFS), 계층 출력 |

> 요약: 루트를 자식보다 먼저 보면 전위, 사이에 끼면 중위, 맨 뒤에 두면 후위.

중위 순회가 "정렬된 출력"을 주는 건 우연이 아니라 이진 탐색 트리(BST)의 "왼쪽 < 나 < 오른쪽" 규칙 덕분이다. 왼쪽(더 작은 값)을 먼저 다 보고, 자신을 보고, 오른쪽(더 큰 값)을 보니 자연히 오름차순이 된다. 후위 순회가 삭제에 쓰이는 이유도 같은 맥락인데, 부모를 지우기 전에 자식부터 정리해야 아직 매달린 자식을 잃어버리지 않기 때문이다.

## 3. 구성요소/구조

```text
        A
       / \
      B   C

전위 : A B C   (나 A -> 왼쪽 B -> 오른쪽 C)
중위 : B A C   (왼쪽 B -> 나 A -> 오른쪽 C)
후위 : B C A   (왼쪽 B -> 오른쪽 C -> 나 A)
```

세 순회 모두 규칙은 하나다. 각 노드에서 "왼쪽 서브트리, 오른쪽 서브트리에 똑같은 규칙을 다시 적용"하고, 그 사이 어디에서 자기 자신을 처리할지만 바꾼다.

| 구성요소 | 하는 일 | 왜 중요한가 |
|:---|:---|:---|
| 루트(Root) | 지금 보고 있는 서브트리의 기준 노드 | 이 노드를 언제 처리하는지가 순회 종류를 결정 |
| 왼쪽 서브트리 | 루트보다 작은 쪽 하위 트리 | 같은 순회 규칙을 재귀로 그대로 적용 |
| 오른쪽 서브트리 | 루트보다 큰 쪽 하위 트리 | 왼쪽을 끝낸 뒤(또는 루트 전후) 방문 |
| 콜 스택(Call Stack) | "돌아와서 마저 할 일"을 쌓아 두는 공간 | 트리 높이 `h`만큼 메모리를 씀 |

> 요약: 순회는 "왼쪽·오른쪽에 같은 규칙 + 나를 언제 처리할지"의 반복이고, 그 되돌아올 경로를 콜 스택이 기억한다.

노드가 `n`개면 모두 한 번씩 방문하므로 시간은 `O(n)`으로 일정하지만, 재귀가 쓰는 메모리는 트리 높이 `h`에 비례하는 `O(h)`다. 균형 잡힌 트리라면 `h`가 `log n`이라 부담이 없지만, 한쪽으로 쏠린 트리에서는 `h`가 `n`에 가까워져 재귀가 깊어지는 것이 다음 문제로 이어진다.

## 4. 문제점 및 개선방안

1. **목적과 순회 방식의 불일치**: 정렬 출력이 필요한데 전위 순회를 쓰면 값이 뒤죽박죽 나오는 것처럼, 목적과 방문 순서가 어긋나면 결과의 의미 자체가 틀어진다.
   - **개선방안**: "정렬 출력은 중위, 삭제·계산은 후위, 복사·직렬화는 전위"처럼 목적별로 순회를 정해 두고 작은 예시 트리로 결과를 먼저 검증한다. (확인: 예시 트리의 출력 순서 일치)

2. **재귀 깊이 초과(스택 오버플로)**: 한쪽으로 쏠린 트리에서는 재귀 깊이가 노드 수에 가까워져 콜 스택이 넘칠 수 있다.
   - **개선방안**: 재귀 대신 명시적 스택을 쓰는 반복 순회로 바꾸거나, 애초에 높이가 낮은 균형 트리를 쓴다. (확인: 최악 재귀 깊이 = 트리 높이)

3. **직렬화·복원의 모호함**: 트리를 한 줄로 저장했다가 되살릴 때, 빈 자식 표시나 중복 키 처리 규칙이 없으면 원래 모양을 유일하게 복원하지 못한다.
   - **개선방안**: 빈 자식을 나타내는 표식(예: `#`)과 중복 키 처리 규칙을 함께 저장한다. (확인: 복원한 트리가 원본과 동일)

## 5. 실무 적용 사례

| 적용 영역 | 어떻게 쓰나 | 무엇으로 효과를 확인하나 |
|:---|:---|:---|
| 컴파일러의 구문 트리(AST) | 후위 순회로 자식(피연산자)을 먼저 계산해 코드·값을 만들어 냄 | 연산 순서, 재귀 깊이 |
| DB·map의 정렬 출력 | 이진 탐색 트리를 중위 순회해 키를 오름차순으로 뽑음 | 출력의 정렬 정확도 |
| 트리·객체의 자원 해제 | 후위 순회로 자식을 모두 정리한 뒤 부모를 해제 | 메모리 누수, 잘못된 참조 여부 |

> 요약: 값을 조립·해제할 때는 후위, 순서대로 뽑을 때는 중위, 모양 그대로 복사할 때는 전위.

## 6. 결론

이진트리 순회는 갈라진 트리를 목적에 맞는 한 줄짜리 처리 순서로 바꾸는 기본기이고, 전위·중위·후위를 가르는 기준은 오직 "루트를 자식보다 언제 처리하느냐" 하나다. 그래서 어떤 순회를 쓸지는 취향이 아니라, 정렬해서 뽑을지·자식부터 정리할지·모양 그대로 복사할지라는 목적과, 트리가 얼마나 깊은지에 따른 재귀 부담을 함께 보고 정해야 한다.
