## 핵심 답안

이진트리 순회는 각 노드가 최대 두 자식을 갖는 트리에서 루트, 왼쪽 서브트리, 오른쪽 서브트리의 방문 순서를 정해 계층 구조를 선형 처리 순서로 바꾸는 방법임.

```text
Preorder : Root -> Left -> Right
Inorder  : Left -> Root -> Right
Postorder: Left -> Right -> Root
```

기술사 답안에서는 순서를 암기하는 데서 끝내지 말고, **루트를 언제 처리하는가가 결과 의미를 어떻게 바꾸는지**를 설명해야 함.

## 순회 방식 비교

| 구분 | 방문 순서 | 의미 | 대표 활용 |
|:---|:---|:---|:---|
| 전위 순회 | Root -> Left -> Right | 부모를 먼저 처리 | 트리 복사, 구조 직렬화, prefix 표현 |
| 중위 순회 | Left -> Root -> Right | 왼쪽과 오른쪽 사이에 부모 처리 | BST 정렬 출력, 범위 순회 |
| 후위 순회 | Left -> Right -> Root | 자식을 먼저 처리 | 트리 삭제, postfix 계산, 하위 결과 집계 |
| 레벨 순회 | 깊이별 좌우 방문 | 가까운 레벨부터 처리 | BFS, 계층 출력 |

이진 탐색 트리(Binary Search Tree, BST)에서 중위 순회는 오름차순 키 순서를 제공하지만, 일반 이진트리에서는 단순한 방문 순서일 뿐 정렬 의미가 없음.

## 구현 관점

| 구현 방식 | 장점 | 주의점 |
|:---|:---|:---|
| 재귀 순회 | 코드가 간결하고 정의와 일치 | 편향 트리에서 호출 스택 초과 |
| 명시적 스택 | 재귀 제한 회피 | 방문 상태 관리 필요 |
| Morris 순회 | 추가 공간 `O(1)` 가능 | 임시 링크 변경으로 구현 난도 높음 |
| 큐 기반 레벨 순회 | 층별 처리 가능 | 넓은 레벨에서 큐 크기 증가 |

모든 노드를 한 번씩 방문하므로 기본 시간복잡도는 `O(n)`이며, 공간복잡도는 재귀 또는 스택 사용 시 트리 높이 `h`에 따라 `O(h)`가 됨.

## 적용 판단

| 목적 | 적합한 순회 | 이유 |
|:---|:---|:---|
| 부모 정보를 먼저 기록 | 전위 | 구조를 먼저 쓰고 자식을 이어 처리 |
| BST 키를 정렬 순서로 출력 | 중위 | 왼쪽 < 루트 < 오른쪽 불변식 활용 |
| 하위 계산 후 부모 계산 | 후위 | 자식 결과가 준비된 뒤 루트 처리 |
| 노드 삭제·해제 | 후위 | 자식을 먼저 제거해야 참조가 안전함 |
| 깊이별 출력·최단 레벨 | 레벨 순회 | 큐로 가까운 노드부터 처리 |

답안에서는 동일한 트리 예시에서 세 순회의 출력이 달라지는 것을 보여주면 구조 이해가 명확해짐.

## 오해와 감점 포인트

- **BST와 일반 이진트리 혼동**: 중위 순회가 정렬 결과를 내는 것은 BST일 때임
- **순회 순서 암기 오류**: 전위·중위·후위는 루트 방문 위치로 구분하면 실수가 줄어듦
- **재귀 스택 누락**: 시간은 `O(n)`이어도 공간은 트리 높이에 의존함
- **null 처리 누락**: 직렬화·복원에서는 null 자식 표시 정책이 필요함
- **중복 키 정책 누락**: 트리 복원 문제에서는 중복 키가 있으면 순회 결과만으로 구조가 모호할 수 있음

## 답안 작성 포인트

1. 정의는 "루트·왼쪽·오른쪽 서브트리의 방문 순서를 정하는 방법"으로 씀
2. 전위·중위·후위를 루트 위치 기준으로 표 비교함
3. BST 중위 순회가 정렬 출력이 되는 이유를 한 줄로 설명함
4. 재귀 구현과 명시적 스택 구현의 공간 차이를 언급함
5. 결론은 "순회 선택은 출력·계산·삭제·직렬화 목적에 따라 달라진다"로 마무리함

> 기술사 관점에서 이진트리 순회는 방문 순서 암기가 아니라 계층 구조를 어떤 업무 의미의 선형 결과로 바꿀지 결정하는 처리 규칙임.
