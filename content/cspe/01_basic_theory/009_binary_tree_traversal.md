# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 이진트리 순회는 트리(008)에 저장된 모든 노드를 중복·누락 없이 한 번씩 방문하는 알고리즘으로, "루트를 언제 방문하느냐"에 따라 전위·중위·후위로 나뉘는 **깊이 우선 탐색(DFS)**의 한 형태다.
- **왜 필요한가**: 배열은 인덱스 0부터 끝까지 순서대로 훑으면 되지만, 트리는 각 노드에서 길이 왼쪽·오른쪽으로 갈라진다. "왼쪽 먼저? 오른쪽 먼저? 나 자신은 언제?"라는 규칙이 없으면 어떤 노드는 여러 번 방문되고 어떤 노드는 아예 방문되지 못한다.
- **핵심 직관**: 루트(나 자신, V)를 방문하는 시점이 이름을 결정한다. 먼저 방문하면 전위(Pre-order), 왼쪽과 오른쪽 사이에 방문하면 중위(In-order), 자식을 모두 본 뒤 마지막에 방문하면 후위(Post-order)다.

## 핵심 용어 정리
| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 깊이 우선 탐색(DFS) | 한 방향으로 갈 수 있는 데까지 파고든 뒤 되돌아오는 탐색 전략(010 참조) | 미로에서 한 길을 끝까지 가보기 |
| V, L, R | 루트(Visit)·왼쪽 서브트리(Left)·오른쪽 서브트리(Right)를 가리키는 약어 | 나·왼쪽 자식·오른쪽 자식 |
| 전위 순회(Pre-order, VLR) | 루트를 먼저, 그다음 왼쪽, 그다음 오른쪽 방문 | 나부터 소개하고 자식들을 차례로 소개 |
| 중위 순회(In-order, LVR) | 왼쪽을 먼저, 그다음 루트, 그다음 오른쪽 방문 | 왼쪽 자식 다음 나, 그다음 오른쪽 자식 |
| 후위 순회(Post-order, LRV) | 왼쪽과 오른쪽을 모두 방문한 뒤 마지막에 루트 방문 | 자식들 일을 다 끝내야 내가 마무리 |
| 레벨 순회(Level-order) | 깊이 우선이 아니라 같은 깊이(레벨) 단위로 왼쪽에서 오른쪽으로 방문, 큐(007) 기반의 너비 우선 탐색(BFS) | 층마다 왼쪽부터 순서대로 점호 |
| 콜 스택(Call Stack) | 재귀 호출이 쌓이는 스택, 함수가 자신을 호출할 때마다 프레임이 push됨 | 되돌아갈 순서를 적어두는 메모지 더미 |
| 추상 구문 트리(AST) | 수식이나 프로그램 코드를 트리 형태로 표현한 것, 컴파일러가 순회하며 해석 | 문장을 문법 구조로 분해한 도식 |
| Prefix/Infix/Postfix | 연산자의 위치에 따른 수식 표기법(전위/중위/후위 표기), 각각 전위·중위·후위 순회 결과와 대응 | 연산자를 앞/가운데/뒤에 쓰는 표기 |

## 깊이 이해

### 세 순회가 같은 트리에서 다른 결과를 내는 이유 — 작은 예로 확인
루트가 A이고 왼쪽 자식이 B, 오른쪽 자식이 C인 트리를 생각하자. 전위(VLR)는 A→B→C, 중위(LVR)는 B→A→C, 후위(LRV)는 B→C→A 순서로 방문한다. 노드도 같고 간선도 같은데 "언제 A를 적을 것인가"만 다르기 때문에 세 결과가 전혀 다른 순서를 만든다. 조금 더 확장해서 수식 `(3+4)*5`를 트리로 만들면 루트가 `*`, 왼쪽 서브트리가 `3+4`, 오른쪽이 `5`다. 전위 순회 결과는 `* + 3 4 5`(전위 표기, Prefix), 중위 순회는 `3 + 4 * 5`(중위 표기, 사람이 쓰는 일반 수식), 후위 순회는 `3 4 + 5 *`(후위 표기, Postfix — 스택 계산기가 쓰는 형태)다. 순회 방식을 정하는 것은 곧 수식을 어떤 표기법으로 읽을지를 정하는 것과 같다.

### 중위 순회가 왜 정렬 결과를 내는가 (BST와 결합 시)
008의 이진 탐색 트리(BST)는 "왼쪽 서브트리는 모두 작은 값, 오른쪽은 모두 큰 값"이라는 규칙을 갖는다. 이 규칙을 가진 트리를 중위(LVR: 왼쪽→루트→오른쪽) 순서로 방문하면, 항상 "더 작은 값들(왼쪽) → 현재 값 → 더 큰 값들(오른쪽)" 순서로 나오게 되고, 이것이 재귀적으로 모든 서브트리에 적용되므로 결과적으로 오름차순 정렬된 값이 O(N)에 나온다. 별도의 정렬 알고리즘 없이 트리 구조 자체가 정렬을 담보한다.

### 후위 순회가 "삭제"와 "용량 계산"에 쓰이는 이유
후위(LRV)는 자식을 모두 처리한 뒤에야 자신을 처리한다. 폴더 용량을 계산할 때 하위 폴더 용량을 다 더해야 상위 폴더 용량이 확정되므로, 반드시 자식(하위 폴더)부터 처리해야 한다 — 후위 순회가 정확히 이 순서를 강제한다. 트리(또는 폴더)를 메모리에서 해제할 때도 마찬가지다. 부모 노드를 자식보다 먼저 지워버리면 자식 노드로 가는 참조를 잃어버려(메모리 누수) 다시는 접근할 수 없게 되므로, 반드시 리프부터 지우고 마지막에 루트를 지워야 한다.

### 재귀 구현과 콜 스택의 관계
세 순회는 모두 자신을 재귀적으로 호출하는 형태로 구현된다. 예를 들어 전위 순회 함수는 "방문(루트) 후 순회(왼쪽) 후 순회(오른쪽)"을 자기 자신을 호출하며 반복한다. 이때 각 재귀 호출은 콜 스택에 프레임을 쌓는데, 트리의 높이가 h라면 최대 h개의 프레임이 쌓인다. 균형 잡힌 트리(008)는 h가 log₂(N) 수준이라 문제없지만, 편향 트리는 h가 N에 근접해 수만~수십만 개 노드를 가진 편향 트리를 재귀로 순회하면 스택 프레임 한계(보통 수천~수만 단계)를 넘어 StackOverflow가 발생할 수 있다. 이때는 재귀 대신 명시적 스택 자료구조(007)를 직접 관리하는 반복문 구현으로 바꿔 힙 메모리를 쓰게 만든다.

### 깊이 우선 순회 vs 레벨 순회
전위·중위·후위는 모두 "부모-자식 종속 관계"를 우선하는 깊이 우선 방식이라 재귀(또는 스택)를 쓴다. 반면 레벨 순회는 "같은 깊이의 형제들을 먼저 다 본다"는 전혀 다른 방식이라 큐(007)를 쓴다 — 시작 노드를 큐에 넣고, 하나씩 꺼내면서 자식을 큐 뒤에 넣는 것을 반복하면 자연히 위쪽 레벨부터 순서대로 나온다. 트리를 화면에 층별로 그리거나(UI 렌더링), 가장 가까운 노드부터 찾아야 할 때(최소 깊이 판단) 레벨 순회가 적합하다.

### 비유
전위는 "나부터 소개하고 자식들을 차례로 소개"하는 자기소개, 중위는 "왼쪽부터 인사시키고 나를 소개한 뒤 오른쪽을 인사시키는" 순서, 후위는 "자식들 뒤치다꺼리를 다 끝내야 비로소 내 할 일을 하는" 부모의 입장과 같다.

## 연결 개념
- 008 트리 구조 — 순회가 대상으로 삼는 트리 자체의 구조(균형·BST 규칙)
- 010 그래프 탐색 — 트리 DFS를 사이클이 있는 그래프로 일반화한 것 (Visited 배열이 추가로 필요)
- 007 스택·큐·덱 — 순회의 실제 구현 엔진(재귀=콜 스택, 레벨 순회=큐)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 비선형 자료구조인 트리 노드를 특정한 재귀적 순서(루트 방문 시점 기준)에 따라 선형화하여 스캔하는 완전 방문 알고리즘이다.
> 2. **가치**: 중위 순회 시 O(N)만으로 정렬된 데이터를 확보하며, 수식 트리 연산 및 AST(추상 구문 트리) 구문 분석 등 컴파일러 설계의 핵심 엔진으로 작용한다.
> 3. **판단 포인트**: 재귀 호출(Call Stack)로 구현되므로 트리가 깊어질 경우 StackOverflow 장애가 발생할 수 있어, 반복문(Iteration) 기반 최적화 통제가 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 이진 트리 순회 기법의 구조적 이해 | V(루트), L(좌), R(우)의 조합 (VLR, LVR, LRV) 메커니즘 | 단순 이름만 적고 방문 순서를 수식화하지 못함 |
| 순회 방식별 실무적 활용도 차이 식별 | 전위(복사), 중위(정렬), 후위(용량 연산/삭제) 활용처 | 세 방식의 차이점을 설명 없이 동일하게 취급 |

> 요약: 트리는 구조가 복잡하여 무작위 탐색이 불가하므로, 목적에 맞게 루트 방문 시점을 제어하는 3대 순회 방식의 취사선택 역량이 중요하다.

## Ⅰ. 개요 및 필요성

- 정의: 이진 트리의 모든 노드를 중복이나 누락 없이 특정 순서에 따라 방문하여 처리(선형화)하는 알고리즘 연산 과정
- 배경: 배열/리스트와 달리 비선형 트리 구조는 다중 분기 경로를 가져 체계적인 스캔 순서 보장 장치 필요
- 필요성: 디렉토리 복제, 구문 트리 연산, 메모리 동적 해제 등 부모-자식 종속성에 따른 처리 우선순위를 강제하기 위해 필수 구현

---

## Ⅱ. 3대 순회 구조 및 메커니즘

```text
트리 방문 -> 루트(V) 방문 시점 제어 -> VLR(전위) / LVR(중위) / LRV(후위) -> 스캔 완료 데이터 반환
```

| 순회 방식 | 노드 방문 순서 | 작동 메커니즘 (재귀 로직) |
|:---|:---|:---|
| 전위 순회 (Pre-order) | 루트(V) -> 좌(L) -> 우(R) | `Process(Node)`, `Visit(L)`, `Visit(R)` |
| 중위 순회 (In-order) | 좌(L) -> 루트(V) -> 우(R) | `Visit(L)`, `Process(Node)`, `Visit(R)` |
| 후위 순회 (Post-order) | 좌(L) -> 우(R) -> 루트(V) | `Visit(L)`, `Visit(R)`, `Process(Node)` |

> 요약: 세 순회 방식 모두 깊이 우선 탐색(DFS)의 파생 형태이며, 서브루틴 내에서 본인(루트) 노드를 언제 처리할 것인가에 따라 이름이 결정된다.

---

## Ⅲ. 동작원리 및 후위 순회 용량 계산 흐름도

```text
부모 연산 요청 -> 좌측 자식 연산 대기 -> 우측 자식 연산 대기 -> 좌+우+본인 용량 병합 -> 부모로 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 좌측 리프 단말 스캔 | 자식이 없을 때까지(Null) 재귀 스택 진입 |
| 2 | 반환 값 대기 | 자식 노드의 처리 값이 콜 스택 최상단에서 리턴 대기 |
| 3 | 서브 트리 병합 완료 | 자식 연산 완료 후 본인 노드 연산 수행 및 병합 |
| 4 | 상위 전파 (Bubble Up) | 최종 연산 결과를 호출자에게 반환하며 스택 메모리 해제 |

> 요약: 후위 순회는 자식이 먼저 처리되어야 부모를 확정할 수 있는 종속성 모델(예: 폴더 용량 집계)의 코어 알고리즘이다.

## Ⅳ. 특징

| 구분 | 깊이 우선 순회 (전위·중위·후위) | 레벨 순회 (Level-order, BFS 기반) | 판단 포인트 |
|:---|:---|:---|:---|
| 방문 순서 기준 | 루트 방문 시점(V의 위치)으로 하위 서브트리를 먼저/나중 탐색 | 트리의 각 깊이(Depth) 단위로 왼쪽에서 오른쪽 수평 방문 | 필요한 결과가 종속 처리인지 계층별 처리인지 |
| 사용 자료구조 | 재귀 콜 스택 또는 명시적 스택(LIFO) | 큐(Queue, FIFO)로 같은 깊이 노드를 순서대로 유지 | 구현 시 스택/큐 선택 |
| 대표 활용 | 정렬 추출·수식 변환·용량 집계 등 부모-자식 종속 처리 | 트리 직렬화 폭 우선 출력, 최소 깊이 탐색, UI 트리 렌더링 | 형제 노드 간 좌우 순서 보존 필요 여부 |
| 공간복잡도 | O(h), h는 트리 높이 | O(w), w는 트리 최대 폭 | 균형 트리(h가 작음) vs 완전 이진트리(w가 큼) |

> 요약: 깊이 우선 순회는 부모-자식 종속 처리에, 레벨 순회는 같은 깊이 단위의 수평 처리·최소 깊이 판단에 적합하며, 트리 형태(폭 vs 높이)에 따라 공간 비용이 달라진다.

## Ⅴ. 순회 방식별 심화 적용 특성 비교

| 비교 축 | 전위 순회 | 중위 순회 | 후위 순회 |
|:---|:---|:---|:---|
| 트리 재구성 (Serialization) | 트리 복제·전송 포맷팅 최적 | 복원 위한 뼈대로 단독 불가 | 단독 불가 (전/중위 결합 필요) |
| 수식 변환 형태 | Prefix (전위 표기법) | Infix (중위 표기법) | Postfix (후위 표기법) |
| 이진 탐색 트리 적용 | 구조 보존 및 루트 식별 | **오름차순 정렬 데이터 추출** | 삭제 전 말단부터 처리(GC) |
| 실무 시스템 맵핑 | UI 컴포넌트 DOM 트리 복제 | RDBMS B-Tree Range Scan | 파일 시스템 하위 용량 집계 |

> 요약: 단순 방문 순서를 넘어 중위 순회는 '정렬', 후위 순회는 '종속성 소멸', 전위 순회는 '구조 복제'라는 고유의 공학적 목적을 띤다.

| 리스크 | 발생 원인 | 대응 기법 | 확인 지표 |
|:---|:---|:---|:---|
| 깊은 트리 StackOverflow | 극단적 편향 트리로 재귀 깊이 O(N) 전락 | 반복문 기반 명시적 스택 자료구조로 전환 | 재귀 호출 깊이(Depth) 임계치 |
| 대용량 순회 지연 | 블록킹 방식으로 노드 전체 대기 | 코루틴을 활용한 지연 평가(Lazy Evaluation) 적용 | 스레드 점유율 및 지연 시간 |

> 요약: 재귀 함수 기반 구현은 우아하나 런타임 OOM 리스크를 유발하므로 상용 환경에서는 메모리 안전성을 통제해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 AST 파서 연산: 프로그래밍 언어 구문 트리를 후위 순회하여 피연산자를 먼저 레지스터에 적재한 후 연산자 기계어 명령 유도
2. 메모리 가비지 컬렉션(GC): 참조 무결성 붕괴 방지를 위해 리프 노드부터 객체 트리를 소거해 올라오는 후위 순회 적용
3. 관계형 DB 인덱스 스캔: RANGE SCAN 시 리프 노드 레벨을 중위 순회와 유사하게 스캔하여 즉시 O(N) 오름차순 레코드 확보

**결론 (2줄):**
- 기술사 판단: 트리 순회는 데이터 모델의 물리적 종속성을 파괴하지 않고 논리적 정합성(정렬, 연산, 복제)을 추출해 내는 제어의 근간이다.
- 향후 방향: 멀티 코어 환경에서 거대 그래프 스캔 속도를 극대화하기 위해 재귀를 다중 스레드로 배분하는 병렬 순회 최적화 연구가 필수적이다.
