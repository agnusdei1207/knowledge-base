## 미리 알고가기

- 이진트리: 각 노드가 최대 두 개의 자식을 갖는 트리 구조임
- 이진 탐색 트리(Binary Search Tree, BST): 왼쪽 서브트리 키 < 루트 키 < 오른쪽 서브트리 키 순서를 만족하는 이진트리임
- 방문: 노드 값을 출력·처리·저장하는 행위임
- 전위 순회: 루트를 왼쪽·오른쪽보다 먼저 방문함(Root -> Left -> Right)
- 중위 순회: 루트를 왼쪽·오른쪽 사이에 방문함(Left -> Root -> Right)
- 후위 순회: 루트를 왼쪽·오른쪽 다음에 방문함(Left -> Right -> Root)

## Ⅰ. 개요

- **정의**: 이진트리 순회는 루트·왼쪽·오른쪽 서브트리의 방문 순서를 정해 계층형 트리를 선형 처리 순서로 변환하는 방법임
- **배경/필요성**: 루트를 언제 방문하느냐가 같은 트리에서도 출력 순서와 연산 의미를 바꾸므로, BST 중위 순회가 오름차순 정렬을, 후위 순회가 자식을 먼저 처리하는 삭제·수식 계산을 만드는 것이 순회 방식 선택의 기준임.
- **비유**: 조직도를 읽을 때 대표를 먼저 볼지, 하위 부서를 다 본 뒤 대표를 볼지, 왼쪽 부서부터 차례로 볼지 정하는 규칙과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 트리 처리 순서 이해 확인 | 전위·중위·후위 순서, 재귀/스택, 적용 사례 | 순회 순서 암기 오류 |

> 요약: 이진트리 순회는 노드 방문 순서를 정의해 계층 구조를 처리 가능한 선형 흐름으로 바꾸는 방법임.

## Ⅱ. 특징/비교

| 판단 기준 | 전위 순회 | 중위 순회 | 후위 순회 |
|:---|:---|:---|:---|
| 방문 순서 | Root -> Left -> Right | Left -> Root -> Right | Left -> Right -> Root |
| 처리 의미 | 부모를 먼저 처리 | 왼쪽과 오른쪽 사이에 부모 처리 | 자식을 먼저 처리 |
| 대표 용도 | 트리 복사, prefix 표현, 직렬화 | BST 정렬 출력, 범위 순회 | 트리 삭제, postfix 계산 |
| 구현 방식 | 재귀 또는 명시적 스택 | 재귀 또는 명시적 스택 | 재귀 또는 두 스택/상태 스택 |
| 선택 기준 | 구조 복원이 우선일 때 | 키 순서 출력이 우선일 때 | 하위 결과 집계가 우선일 때 |

> 요약: 순회 방식은 동일한 트리라도 부모를 언제 처리하는지에 따라 결과와 적용 목적이 달라짐.

- 레벨 순회는 큐로 깊이 순서를 유지하는 너비 우선 탐색(Breadth-First Search, BFS)이므로, 깊이 우선 탐색(Depth-First Search, DFS) 방식인 전위·중위·후위와 구분해야 함
- 전위·중위·후위는 모든 노드를 한 번씩 방문하므로 시간 복잡도가 노드 수 `n` 기준 `O(n)`임
- 재귀 구현은 코드가 짧지만 트리 높이 `h`가 커지면 호출 스택 깊이가 `O(h)`까지 늘어 스택 오버플로 위험이 있음

## Ⅲ. 구성요소

```text
          +------+
          | Root |
          +------+
           /    \
          v      v
     +------+  +------+
     | Left |  | Right|
     +------+  +------+
         \        /
          v      v
        +----------+
        | VisitRule|
        +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 루트 노드 | 현재 서브트리의 기준 노드이며 방문 위치가 순회 종류를 결정함 | 부서장 |
| 왼쪽 서브트리 | 현재 노드의 왼쪽 하위 구조이며 재귀적으로 같은 규칙을 적용함 | 왼쪽 팀 |
| 오른쪽 서브트리 | 현재 노드의 오른쪽 하위 구조이며 왼쪽 처리 후 또는 전후에 방문함 | 오른쪽 팀 |
| 방문 규칙 | 루트 처리를 왼쪽·오른쪽 처리 전, 중간, 후 중 어디에 둘지 정함 | 회의 발언 순서 |
| 호출 스택 | 재귀 또는 명시적 스택으로 되돌아갈 경로를 보존함 | 방문 기록표 |

> 요약: 이진트리 순회는 루트와 두 서브트리에 같은 방문 규칙을 반복 적용하는 구조임.

- 순회 대상이 이진 탐색 트리인지 일반 이진트리인지에 따라 중위 결과의 의미가 달라짐
- null 자식을 방문하지 않는 규칙과 null 표시를 출력하는 직렬화 규칙은 구분해야 함
- 반복 구현에서는 스택에 노드와 방문 상태를 함께 저장하면 후위 순회를 안전하게 처리할 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 노드확인 | ---> | 좌측처리 | ---> | 루트처리 | ---> | 우측처리 |
+----------+      +----------+      +----------+      +----------+
      |                 ^                 |                 |
      v                 |                 v                 v
+----------+      +----------+      +----------+      +----------+
| null판정 |      | 순서규칙 |      | 방문결과 |      | 재귀복귀 |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 트리 종류, 방문 결과의 목적, 전위·중위·후위 중 필요한 순서를 확인함
2. **종료 조건 확인** - 현재 노드가 null이면 더 방문하지 않고 이전 호출로 복귀함
3. **순서 규칙 적용** - 선택한 순회 방식에 따라 루트 처리와 왼쪽·오른쪽 재귀 호출 위치를 배치함
4. **결과 반환** - 방문한 노드 값, 계산 결과, 직렬화 결과를 누적하고 스택 또는 재귀 호출을 정리함

> 요약: 순회 절차는 null 종료 조건을 두고 같은 방문 규칙을 모든 서브트리에 재귀적으로 적용하는 흐름임.

- 전위와 중위 결과가 함께 있으면 중복 키가 없다는 조건에서 트리 구조 복원이 가능함
- 후위 순회는 자식 리소스를 먼저 해제해야 하는 메모리 정리에서 안전함
- 반복 순회는 재귀 깊이 제한이 있는 런타임에서 필요함

## Ⅴ. 문제점

- **P1 깊은 트리의 스택 초과**: 편향 트리에서 재귀 깊이가 노드 수에 가까워져 호출 스택 한계를 초과할 수 있음
- **P2 순회 목적 불일치**: BST 정렬 출력에 전위 순회를 쓰는 등 방문 순서와 목적이 맞지 않으면 결과 의미가 틀어짐
- **P3 중복·null 처리 모호성**: 중복 키와 null 자식 표시 정책이 없으면 직렬화나 트리 복원 결과가 모호해질 수 있음

> 요약: 이진트리 순회는 방문 순서 자체보다 깊이, 목적, 경계 표시 정책을 명확히 해야 누락·중복 없이 동작함.

## Ⅵ. 개선방안

- **P1 대응**: 명시적 스택 기반 반복 순회, 균형 트리 사용, 재귀 깊이 제한 검사를 적용함 (확인: 편향 트리 테스트)
- **P2 대응**: 사용 목적별 순회 방식을 표준 매핑하고 단위 테스트에서 기대 방문 순서를 검증함 (확인: 대표 트리 방문 결과)
- **P3 대응**: 중복 키 정책과 null 마커 직렬화 규칙을 문서화하고 복원 테스트를 수행함 (확인: serialize/deserialize 동치성)

> 요약: 순회 개선은 깊이 위험을 줄이고 목적별 방문 규칙과 경계 표현을 명확히 하는 방향임.

## Ⅶ. 전망

- **발전 방향**: 컴파일러의 추상 구문 트리(Abstract Syntax Tree, AST), JSON(JavaScript Object Notation)·XML(Extensible Markup Language) 문서, 데이터베이스 실행 계획 트리 같은 계층 구조 처리에서 순회는 기반 원리로 계속 활용됨
- **기술사적 판단**: 순회 순서를 암기하는 데서 그치지 말고 결과가 정렬, 계산, 삭제, 직렬화 중 무엇을 의미하는지 연결해야 함
- **기술사 제언**: 답안에서는 전위·중위·후위를 같은 트리 예시로 비교하고 각 방식의 적용 목적을 한 줄씩 제시하는 것이 효과적임
