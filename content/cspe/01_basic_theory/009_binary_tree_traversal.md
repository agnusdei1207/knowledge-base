# 009. 이진트리 순회 — 전위·중위·후위 (Binary Tree Traversal) [출제:126회]

## 1. 개요

- **정의/개념**: 이진트리 순회는 모든 노드를 한 번씩 방문하되, 루트를 좌·우 자식보다 언제 처리하느냐로 계층 구조를 선형 순서로 바꾸는 방법이다.
- **배경/필요성**: 같은 트리라도 루트를 방문하는 시점에 따라 정렬 출력·구조 복원·삭제·수식 계산 결과가 달라지므로, 목적에 맞는 순회를 골라야 한다.

## 2. 특징 및 비교

순회의 "전·중·후"는 곧 루트를 처리하는 시점을 뜻한다. 자식은 항상 왼쪽부터 보고, 그 사이 어디에 루트를 두느냐만 다르다.

| 순회 | 방문 순서 | 결과·용도 |
|:---|:---|:---|
| 전위(Preorder) | 루트 → 좌 → 우 | 트리 복사·직렬화 |
| 중위(Inorder) | 좌 → 루트 → 우 | BST에서 정렬 출력 |
| 후위(Postorder) | 좌 → 우 → 루트 | 삭제, 후위 표기식 계산 |
| 레벨(Level) | 층별(BFS) | 계층 출력 |

> 요약: 루트를 먼저 두면 전위, 사이에 두면 중위, 뒤에 두면 후위.

중위 순회가 정렬 결과를 주는 것은 BST의 "왼쪽 < 나 < 오른쪽" 규칙 때문이고, 후위 순회가 삭제에 쓰이는 것은 부모보다 자식을 먼저 정리해야 매달린 자식을 잃지 않기 때문이다.

## 3. 구성요소/구조

```text
        A
       / \
      B   C

전위 A B C / 중위 B A C / 후위 B C A
```

세 순회 모두 "좌·우 서브트리에 같은 규칙을 재귀 적용하고, 그 사이 어디서 루트를 처리할지"만 바꾼다. 노드가 `n`개면 시간은 `O(n)`으로 같고, 재귀 복귀 경로를 쌓는 콜 스택 때문에 메모리는 트리 높이 `h`에 비례하는 `O(h)`다.

- **루트**: 처리 시점이 순회 종류를 결정
- **좌·우 서브트리**: 같은 규칙을 재귀로 적용
- **콜 스택**: 복귀 경로 저장, 높이 `h`만큼 사용

## 4. 문제점 및 개선방안

1. **목적-순회 불일치**: 정렬 출력에 전위를 쓰는 식으로 목적과 순서가 어긋나면 결과의 의미가 틀어진다.
   - **개선방안**: 정렬은 중위, 삭제·계산은 후위, 복사는 전위로 매핑하고 예시 트리로 검증 (확인: 출력 순서 일치)
2. **재귀 깊이 초과**: 편향 트리에서 재귀 깊이가 노드 수에 근접해 콜 스택이 넘칠 수 있다.
   - **개선방안**: 명시적 스택 기반 반복 순회 또는 균형 트리 사용 (확인: 최악 깊이 = 트리 높이)
3. **직렬화 모호성**: 빈 자식 표시나 중복 키 규칙이 없으면 원본을 유일하게 복원할 수 없다.
   - **개선방안**: 널 마커와 중복 키 정책을 함께 저장 (확인: 복원 트리 = 원본)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 컴파일러 AST | 후위 순회로 피연산자를 먼저 계산해 코드 생성 | 연산 순서, 스택 깊이 |
| DB·map 정렬 출력 | BST 중위 순회로 키를 오름차순 출력 | 정렬 정확도 |
| 자원 해제 | 후위 순회로 자식 정리 후 부모 해제 | 메모리 누수, 참조 오류 |

> 요약: 조립·해제는 후위, 순서 출력은 중위, 모양 복사는 전위.

## 6. 결론

이진트리 순회를 가르는 기준은 "루트를 자식보다 언제 처리하느냐" 하나이며, 어떤 순회를 쓸지는 목적(정렬·삭제·복원)과 트리 높이에 따른 재귀 부담을 함께 보고 정한다.
