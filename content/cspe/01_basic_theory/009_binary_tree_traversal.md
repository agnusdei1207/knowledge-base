## Ⅰ. 개요
- **정의**: 이진트리의 모든 노드를 특정 순서 규칙에 따라 한 번씩 방문하는 연산
- **배경/필요성**: 트리에 저장된 데이터를 읽거나 변환하려면 노드 방문 순서가 명확해야 하며, 순서에 따라 출력·복원·연산 결과가 달라짐
- **비유**: 건물 점검 시 "지붕→왼쪽 벽→오른쪽 벽" 순서로 돌지, "왼쪽 벽→지붕→오른쪽 벽" 순서로 돌지에 따라 점검 기록이 달라지는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 네 가지 순회 방식의 방문 순서 차이 이해 | 전위·중위·후위·레벨 순회의 루트 방문 시점 | 중위 순회가 BST에서 정렬 출력을 보장하는 이유 명시 |

> 요약: 루트 방문 시점에 따라 전위·중위·후위로 구분되며, BST 중위 순회는 정렬 결과를 출력함

## Ⅱ. 구성요소
```text
        [Root]
       /      \
   [Left]    [Right]
   /    \    /    \
 [LL] [LR] [RL] [RR]

순회 방식 결정 기준: Root 방문 시점
  Pre  : Root -> Left -> Right
  In   : Left -> Root -> Right
  Post : Left -> Right -> Root
  Level: 층별 좌 -> 우 (큐 사용)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 전위 순회(Preorder) | 루트를 먼저 방문한 뒤 좌·우 서브트리를 재귀 탐색함 | 책 목차를 장→절→항 순서로 읽는 방식 |
| 중위 순회(Inorder) | 좌 서브트리 → 루트 → 우 서브트리 순으로 방문함 | 수식 트리에서 괄호 없이 중위 표기를 복원하는 방식 |
| 후위 순회(Postorder) | 좌·우 서브트리를 모두 방문한 뒤 루트를 마지막에 처리함 | 폴더 삭제 시 하위 파일을 먼저 지우고 폴더를 삭제하는 방식 |
| 레벨 순회(Level-order) | 큐를 사용하여 같은 깊이의 노드를 좌→우 순서로 방문함 | 건물 1층부터 한 층씩 올라가며 방을 점검하는 방식 |

> 요약: 루트 방문 시점(먼저/중간/나중)과 탐색 방향(깊이/너비)으로 네 가지 순회가 구분됨

## Ⅲ. 절차
```text
[트리 입력] --> [순회 방식 선택] --> [자료구조 초기화] --> [노드 방문 및 처리]
                                        |                       |
                                  재귀: 콜스택            방문 결과 수집
                                  반복: 명시적 스택/큐
```
- 1단계: 트리 루트 노드와 순회 방식(전위/중위/후위/레벨)을 입력받음
- 2단계: 재귀 방식이면 콜스택을 활용하고, 반복 방식이면 스택(전위·중위·후위) 또는 큐(레벨)를 초기화함
- 3단계: 선택한 순서 규칙에 따라 현재 노드를 방문하고 결과를 기록함
- 4단계: 모든 노드 방문이 완료되면 결과를 반환함. 시간복잡도 O(n), 공간복잡도 O(h) (h는 트리 높이)

> 요약: 순회 방식에 따라 스택 또는 큐를 활용하여 모든 노드를 O(n)에 방문함

## Ⅳ. 문제점
- 재귀 깊이 초과: 편향 트리(skewed tree)에서 높이가 n에 도달하면 콜스택 오버플로가 발생함
- 순회 방식 혼동: 전위·중위·후위의 방문 순서를 잘못 적용하면 트리 복원이나 연산 결과가 오류를 냄
- 공간 비효율: 레벨 순회 시 완전 이진트리의 마지막 레벨 노드 수(n/2)만큼 큐 메모리가 필요함

> 요약: 편향 트리의 스택 오버플로, 순서 혼동에 의한 오류, 레벨 순회의 메모리 부담이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 반복(iterative) 방식으로 전환하여 명시적 스택을 사용하고 콜스택 오버플로를 회피함
2. 중기: 순회 결과를 시각화하는 검증 도구를 활용하여 방문 순서 오류를 사전에 탐지함
3. 장기: Morris Traversal(스레드 이진트리) 기법을 적용하여 O(1) 추가 공간으로 중위·전위 순회를 수행함

> 요약: 반복 변환으로 안정성을 확보하고, Morris Traversal로 공간 효율을 극대화함

## Ⅵ. 전망
- 발전 방향: 대규모 트리 처리에서 병렬 순회·외부 메모리 순회 기법의 적용이 확대됨
- 기술사적 판단: 트리 순회는 컴파일러 구문 분석, DB 인덱스 탐색, 파일시스템 탐색 등 핵심 기반 알고리즘으로 중요도가 지속됨
- 기술사 제언: 그래프 탐색(010 참조)과 연계하여 순회 알고리즘의 확장 적용 능력을 갖출 필요가 있음
