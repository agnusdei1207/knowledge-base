# 📖 【암기용】 개념 완전 이해

> 목적: 전위·중위·후위 순회를 방문 순서 암기가 아니라 연산 위치 차이로 이해하게 만든다.

## 한눈에
- **개요**: 이진트리의 모든 노드를 규칙에 따라 한 번씩 방문하는 방법
- **왜 필요한가**: 트리 저장, 수식 계산, 정렬 출력처럼 방문 순서가 결과를 결정함
- **핵심 직관**: 루트 작업을 왼쪽·오른쪽 방문 사이의 어느 시점에 하느냐가 순회 이름을 결정함

## 깊이 이해
- **배경·문제의식**: 트리는 선형 순서가 없으므로 처리 순서가 필요함. 순회는 재귀 구조를 선형 결과로 바꾸는 규칙임
- **작동 원리**: 전위는 Root-Left-Right라 복사·직렬화에 적합함. 중위는 Left-Root-Right라 BST에서 정렬 순서를 출력함. 후위는 Left-Right-Root라 자식 처리 후 부모를 처리하는 계산·삭제에 적합함
- **비유**: 조직도를 읽을 때 사장을 먼저 소개하면 전위, 하위 조직을 보고 책임자를 말하면 중위, 모든 팀 업무를 끝낸 뒤 부서장을 평가하면 후위임
- **구체 예시**: 루트 A, 왼쪽 B, 오른쪽 C이면 전위 A-B-C, 중위 B-A-C, 후위 B-C-A임
- **흔한 오해·주의점**: 순회는 이진트리에서만 쓰는 것이 아님. 일반 트리도 DFS 전위·후위 순회가 가능하나, 중위는 이진트리의 좌/우 구조와 밀접함

## 연결 개념
- DFS — 재귀·스택 방문 / 이진 탐색 트리 — 중위 오름차순 출력 / 수식 트리 — 후위 postfix 계산

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진트리 순회는 루트·왼쪽 서브트리·오른쪽 서브트리의 방문 순서를 규정하는 DFS 기반 방문 절차이다.
> 2. **가치**: 모든 노드를 정확히 1회 방문해 시간복잡도 O(n), 재귀 호출 스택은 트리 높이 h만큼 사용한다.
> 3. **판단 포인트**: 복사·직렬화는 전위, 정렬 출력은 중위, 계산·삭제는 후위를 선택한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 이진트리의 노드 방문 순서를 정하는 규칙
- 배경: 트리는 자연 순서가 없으므로 탐색·출력·계산 목적에 맞는 방문 규칙이 필요함
- 필요성: 순회 결과는 구문트리, DB 인덱스 검증, 직렬화에 활용됨

---

## Ⅱ. 구조 및 구성요소

```text
Tree example: A -> left B -> left D / right E
              A -> right C
Preorder: A B D E C
Inorder: D B E A C
Postorder: D E B C A
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Root | 현재 서브트리 기준 노드 | 방문 위치가 순회 유형 결정 |
| Left Subtree | 먼저 또는 중간에 방문 | 재귀 호출 대상 |
| Right Subtree | 마지막 또는 중간에 방문 | 재귀 호출 대상 |
| Call Stack | 재귀 상태 보관 | 공간복잡도 O(h) |

> 요약: 순회 유형은 동일한 트리에서 Root 방문 위치만 바꿔 서로 다른 선형 결과를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
노드 입력 -> NULL 검사 -> (Root 방문 위치 선택) -> Left 순회 -> Right 순회 -> 결과 생성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 현재 노드 NULL 여부 확인 | NULL이면 즉시 반환 |
| 2 | 전위면 Root 먼저 방문 | R-L-R 순서 중 첫 R 처리 |
| 3 | Left, Right 재귀 순회 | 각 노드 1회 방문 |
| 4 | 중위·후위면 Root 위치에 맞춰 방문 | BST 중위 결과 오름차순 확인 |

> 요약: 순회는 NULL 종료 조건과 재귀 호출 순서만으로 O(n) 방문 결과를 생성한다.

---

## Ⅳ. 특징

| 구분 | 전위(Preorder) | 중위(Inorder) | 후위(Postorder) |
|:---|:---|:---|:---|
| 방문 순서 | Root-Left-Right | Left-Root-Right | Left-Right-Root |
| 시간복잡도 | O(n) | O(n) | O(n) |
| 공간복잡도 | O(h) 재귀 스택 | O(h) 재귀 스택 | O(h) 재귀 스택 |
| 활용 | 트리 복사, prefix | BST 정렬 출력 | postfix, 메모리 해제 |

> 요약: 세 순회 모두 모든 노드를 1회 방문하지만, 루트 처리 시점에 따라 적용 목적이 달라진다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 반복 방식 | 재귀 순회 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 명시적 Stack 사용 | Call Stack 사용 | 깊이 10만 이상이면 반복 방식 |
| 비용/성능 | O(n), 스택 O(h) | O(n), 콜스택 O(h) | 언어별 stack limit 확인 |
| 운영/위험 | 코드 복잡도 증가 | stack overflow 위험 | 편향 트리 입력 검증 |

> 요약: 순회 방식은 방문 순서보다 트리 높이와 스택 한계를 기준으로 재귀·반복을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Stack Overflow | 편향 트리 높이 h=n | 명시적 stack, tail recursion 제거 | 최대 깊이, 예외 건수 |
| 방문 순서 오류 | Root 처리 위치 혼동 | 전위/중위/후위 테스트 벡터 | 순회 결과 일치율 |
| 복원 불가 | 중복 키·순회 조합 부족 | 전위+중위 또는 후위+중위와 unique key 사용 | 복원 실패 건수 |

> 요약: 순회 리스크는 스택 깊이, 방문 순서, 복원 조건이며 테스트 벡터로 검증한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시간 | 노드 n개 1회 방문, O(n) | 방문 카운터 |
| 공간 | 스택 사용량 O(h) | 프로파일러 |
| 정확도 | BST 중위 결과 단조 증가 | 단위 테스트 |

> 요약: 성공 기준은 O(n) 방문, O(h) 공간, 목적별 결과 검증이다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. BST 검증: 중위 순회 결과가 단조 증가인지 확인해 정렬 규칙 위반 노드 탐지
2. 수식 평가: 후위 순회로 postfix 토큰 생성 후 스택 기반 계산 수행
3. 직렬화·복원: 전위 순회 + NULL 마커 또는 전위+중위 조합으로 트리 구조 복원

**결론 (2줄):**
- 기술사 판단: 순회 선택은 자료구조 유형이 아니라 결과 사용 목적(출력·계산·복원)에 따라 결정함
- 향후 방향: 깊이 10만 이상 편향 트리에서는 재귀 대신 명시적 스택을 사용해 stack overflow를 방지해야 함
