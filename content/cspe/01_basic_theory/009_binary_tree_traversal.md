## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진트리 순회(Binary Tree Traversal)는 트리의 모든 노드를 정확히 한 번씩 방문하는 절차이며, 부모·왼쪽 자식·오른쪽 자식을 방문하는 상대적 순서에 따라 전위(Pre-order: 부→좌→우)·중위(In-order: 좌→부→우)·후위(Post-order: 좌→우→부)·레벨(Level-order: 층별)로 구분됨.
> 2. **가치**: 중위 순회는 BST의 원소를 정렬 순서로 출력하고, 후위 순회는 자식을 먼저 처리해야 하는 연산(트리 높이 계산, 하위 구조 선삭제, 수식 평가)에 사용되며, 전위 순회는 부모를 먼저 생성해야 하는 복제·직렬화에 사용됨. 순회 방식의 선택이 곧 문제 해결 전략을 결정함.
> 3. **융합**: 컴파일러의 구문 트리(AST) 코드 생성(후위), 파일 시스템·컨테이너 계층의 재귀적 정리(후위), 데이터베이스 인덱스의 범위 스캔(중위), 트리 구조 데이터의 직렬화(전위) 등 트리를 다루는 전 분야에서 순회 패턴이 기반 원리로 작동함.

---

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| 전위 순회 (Pre-order) | 부모→왼쪽→오른쪽 순으로 방문 | 안내원이 먼저 서고 좌측·우측 관람객이 뒤따르는 동선 |
| 중위 순회 (In-order) | 왼쪽→부모→오른쪽 순으로 방문, BST에서는 정렬 순서를 출력 | 사전을 가나다순으로 읽는 것 |
| 후위 순회 (Post-order) | 왼쪽→오른쪽→부모 순으로 방문, 자식을 먼저 처리해야 하는 연산에 적합 | 부하가 보고를 마친 후 상급자가 최종 결재하는 순서 |
| 레벨 순회 (Level-order) | 같은 깊이의 노드를 왼쪽부터 층별로 방문(BFS 방식, 010 참조) | 건물을 1층부터 한 층씩 순서대로 점검 |
| 중위 선행자 (Inorder Predecessor) | 특정 노드를 기준으로 중위 순회에서 바로 앞에 방문되는 노드(그 노드 왼쪽 서브트리의 최우측 노드) | 줄 서기에서 내 바로 앞사람 |
| Morris Traversal | 중위 선행자에 임시 링크(스레드)를 걸어 O(1) 공간에서 순회하는 기법 | 갈림길에 임시 표식을 남기고 돌아온 뒤 표식을 지우는 방식 |

> 요약: 순회 방식은 부모를 언제 방문하는가(먼저/중간/나중/층별)로 구분되며, Morris Traversal은 그 방문 순서를 추가 메모리 없이 구현하는 기법이다.

## Ⅰ. 개요 및 필요성

- **개념**: 트리 순회는 재귀적으로 정의됨. 전위는 `방문(node) → 순회(left) → 순회(right)`, 중위는 `순회(left) → 방문(node) → 순회(right)`, 후위는 `순회(left) → 순회(right) → 방문(node)` 순서를 따름. 레벨 순회는 큐 기반 BFS로 같은 깊이의 노드를 왼쪽부터 방문함(BFS 일반론은 010 그래프 탐색 참조).
- **필요성**: 트리는 비선형 자료구조이므로 배열·연결 리스트처럼 정해진 순서로 따라갈 수 없음. "부모를 언제 방문하는가"를 먼저 정의해야 모든 노드를 누락 없이 체계적으로 처리 가능함.
- **비유**: 순회 방식은 미술관 관람 루트와 같음. 전위는 "입구에서 왼쪽으로 쭉 본 뒤 오른쪽"(안내원 동선), 중위는 "작은 작품부터 큰 작품 순"(크기순 감상), 후위는 "구석 작품부터 보고 마지막에 메인 전시"(청소부 동선)에 해당함.
- **등장 배경 및 발전 과정**:
  1. 전위·후위 순회는 수식 트리(Expression Tree)의 프리픽스(전위 표기, Polish Notation)·포스트픽스(후위 표기, Reverse Polish Notation) 출력과 직접 대응함. 프리픽스 표기법은 1920년대 폴란드 논리학자 얀 우카시에비치(Jan Łukasiewicz)가 명제논리 표기를 위해 고안함.
  2. Morris Traversal(1979): Joseph M. Morris가 "Traversing Binary Trees Simply and Cheaply"에서 스레디드 트리(Threaded Tree) 개념을 응용하여 O(1) 공간으로 중위 순회를 수행하는 기법을 발표함.

```text
+-----------------------------------------------------------------------+
|         이진트리 순회 4종의 방문 순서 비교                            |
+-----------------------------------------------------------------------+
|                                                                       |
|  예시 트리:                                                           |
|              (1)                                                     |
|             /   \                                                    |
|           (2)   (3)                                                  |
|           / \     \                                                  |
|         (4) (5)   (6)                                                |
|                                                                       |
|  [전위 — 부모 먼저]   visit → left → right                          |
|  결과: 1 → 2 → 4 → 5 → 3 → 6                                        |
|                                                                       |
|  [중위 — 부모 중간]   left → visit → right                          |
|  결과: 4 → 2 → 5 → 1 → 3 → 6                                        |
|                                                                       |
|  [후위 — 부모 마지막] left → right → visit                          |
|  결과: 4 → 5 → 2 → 6 → 3 → 1                                        |
|                                                                       |
|  [레벨 — 층별(BFS)]   같은 깊이를 왼→오로                            |
|  결과: 1 → 2 → 3 → 4 → 5 → 6                                        |
+-----------------------------------------------------------------------+
```

핵심은 부모 노드를 언제 방문하느냐임. 전위는 부모를 먼저 방문하므로 루트 1이 첫 번째이고, 중위는 왼쪽을 모두 본 후 부모를 방문하므로 가장 왼쪽인 4가 첫 번째이며, 후위는 자식을 모두 처리한 후 부모를 방문하므로 루트 1이 마지막임. BST에서 중위 순회 결과가 오름차순이 되는 성질이 이 순서 규칙에서 직접 도출됨.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소 — 순회 구현 방식별 비교

| 구현 방식 | 방문 순서 제어 | 공간복잡도 | 트리 구조 변경 | 비고 |
|:---|:---|:---|:---|:---|
| 재귀 구현 | 함수 호출 순서(시스템 콜 스택) | O(H) | 없음 | 스택 메커니즘 자체는 007 스택·큐·덱 참조 |
| 반복(명시적 스택) 구현 | push·pop 순서로 재현 | O(H) | 없음 | 명시적 스택 활용법은 007 참조 |
| Morris Traversal | 중위 선행자에 임시 스레드 연결 | O(1) | 순회 중 일시 변경 후 즉시 복원 | 읽기 전용 트리·멀티스레드 환경에는 부적합 |

> 요약: 세 구현 모두 방문 결과(전위·중위·후위)는 동일하며, 방문 순서를 제어하는 수단(콜 스택·명시적 스택·임시 스레드)과 공간복잡도만 다르다. H는 트리 높이로, 균형·편향 여부에 따른 값은 008 트리 구조 참조.

### 핵심 원리 — Morris Traversal의 스레딩 메커니즘

```text
+-----------------------------------------------------------------------+
|      Morris 중위 순회 — 예시 트리 2(좌:1, 우:3)                       |
+-----------------------------------------------------------------------+
|                                                                       |
|  원본:        2       1단계: curr=2, 왼쪽 서브트리 있음               |
|              / \            왼쪽의 최우측 노드(1=중위 선행자) 탐색    |
|             1   3            1.right가 비어있음 → 1.right=curr(2)     |
|                               (임시 스레드 연결), curr = curr.left(1) |
|                                                                       |
|  스레드 연결: 2      2단계: curr=1, 왼쪽 없음 → visit(1)              |
|              / \           curr = curr.right → 스레드 따라 2로 복귀  |
|             1   3                                                    |
|              \                                                       |
|               ⇢ 2 (임시 스레드)                                      |
|                                                                       |
|  3단계: curr=2, 왼쪽(1)의 최우측 노드가 이미 curr(2)를 가리킴(스레드 발견)|
|         → 스레드 제거(1.right=None), visit(2), curr=curr.right(3)    |
|  4단계: curr=3, 왼쪽 없음 → visit(3), curr=None → 종료                |
|                                                                       |
|  방문 순서: 1 → 2 → 3 (정상 중위 순서, 순회 종료 후 트리는 원본 복원) |
+-----------------------------------------------------------------------+
```

- curr의 왼쪽 서브트리가 있으면 그 서브트리의 최우측 노드(중위 선행자)를 찾아 curr를 가리키는 임시 스레드를 연결한 뒤 왼쪽으로 이동함.
- 왼쪽 서브트리가 없거나 이미 스레드가 연결되어 있으면 현재 노드를 방문하고, 스레드가 있었다면 즉시 제거하여 트리를 원본 상태로 복원함.
- 각 간선을 스레드 생성 시 1회, 스레드를 따라 복귀할 때 1회로 최대 2회만 통과하므로 시간복잡도는 O(N)으로 유지되면서, 재귀·명시적 스택을 전혀 사용하지 않아 공간복잡도가 O(1)로 낮아짐.

## Ⅲ. 비교 및 연결

### 비교 1: 전위·중위·후위·레벨 순회 비교

| 구분 | 전위(Pre-order) | 중위(In-order) | 후위(Post-order) | 레벨(Level-order) |
|:---|:---|:---|:---|:---|
| 방문 순서 | 부모→좌→우 | 좌→부모→우 | 좌→우→부모 | 깊이 순 층별(BFS, 010 참조) |
| 대표 활용 | 트리 복제, 직렬화, 수식의 전위(Prefix) 표기 | BST 오름차순 출력, 범위 스캔 | 트리 높이 계산, 하위 구조 선삭제, 수식의 후위(Postfix) 표기 평가 | 최소 깊이 탐색, 층별 출력 |
| 트리 복원 시 루트 위치 | 결과의 맨 앞 | 좌우 분할 기준 | 결과의 맨 끝 | 복원에 단독 사용 안 함 |
| 대표 문제 | LeetCode 144, 297 | LeetCode 94 | LeetCode 145 | LeetCode 102 |

> 요약: 네 순회의 차이는 "부모를 언제 방문하는가"(전/중/후)와 "층별 여부"(레벨)이며, 이 시점 차이가 적용 문제를 결정한다.

### 비교 2: 순회 조합별 트리 복원 가능 여부

| 조합 | 복원 가능 여부 | 이유 |
|:---|:---|:---|
| 전위 + 중위 | 가능 | 전위의 첫 원소가 루트, 중위에서 루트 기준 좌우 서브트리 분할 |
| 후위 + 중위 | 가능 | 후위의 마지막 원소가 루트, 중위에서 좌우 분할 |
| 전위 + 후위 | 일반 이진트리는 불가, 완전 이진트리(Full Binary Tree, 모든 노드의 자식이 0개 또는 2개)는 유일 복원 가능 | 좌우 서브트리 경계를 구분할 중위 정보가 없음(LeetCode 889) |
| 중위만 | 불가 | 루트를 특정할 근거가 없음 |

> 요약: 트리 복원 가능 여부는 중위 순회 포함 여부가 결정하며, 중위가 없으면 좌우 서브트리 경계를 나눌 기준이 사라진다.

### 과목 융합 관점
- **컴파일러**: 소스 코드의 추상 구문 트리(AST)를 후위 순회하여 피연산자(리프)를 먼저 스택에 push하고 연산자(부모) 노드에서 pop·연산하는 스택 기반 바이트코드를 생성함.
- **파일 시스템**: `du -sh` 계열 명령은 디렉토리 크기를 후위 순회로 계산함 — 하위 파일·디렉토리의 크기를 먼저 합산한 후 현재 디렉토리 크기를 결정함.
- **데이터베이스**: B+Tree 인덱스의 범위 스캔은 리프 노드가 연결 리스트로 이어진 구조를 순차 접근하는 방식이며, 이 접근 순서가 중위 순회의 정렬 출력 원리와 동일함(B+Tree 내부 구조는 008 트리 구조 참조).

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — JSON 트리 직렬화 (전위)**: REST API에서 조직도·카테고리 계층 같은 트리형 데이터를 전위 순회로 직렬화하면 부모 노드를 먼저 출력한 뒤 자식 배열을 중첩시키는 구조가 되어, JSON의 중첩 객체 표현과 자연스럽게 일치함.
2. **시나리오 — Linux cgroup 계층 정리 (후위)**: cgroup 계층에서 상위 cgroup 디렉토리를 제거하려면 하위 cgroup이 먼저 비워지고 삭제되어야 하며, 이는 자식을 먼저 처리하는 후위 순회와 동일한 종속 순서를 가짐.

### 도입 체크리스트
- **기술적**: 문제가 "부모 먼저"(전위), "정렬 순서"(중위), "자식 먼저"(후위) 중 어떤 요구인지 판별했는가.
- **운영 및 보안적**: 재귀 깊이가 트리 높이에 비례하여 시스템 콜 스택 한계를 초과할 가능성이 있는가(예: 편향 트리에서 재귀 제한 초과).

### 안티패턴
- **후위 문제에 전위 적용**: 디렉토리 크기 계산에 전위 순회를 적용하면 현재 디렉토리 방문 시점에 하위 디렉토리 크기가 아직 집계되지 않아 정확한 값을 얻을 수 없음.
- **BST 정렬 출력에 전위·후위 사용**: 오름차순 출력을 보장하는 순회는 중위뿐이며, 전위·후위는 정렬 순서를 보장하지 않음.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 순회 미활용 | 적절한 순회 활용 | 개선 효과 |
|:---|:---|:---|:---|
| 정량 | BST 정렬 출력에 별도 정렬 알고리즘 적용, O(N log N) | 중위 순회로 직접 오름차순 출력, O(N) | 별도 정렬 단계 제거로 시간복잡도 한 단계 감소 |
| 정량 | 트리 직렬화 시 임시 배열에 전체 노드를 먼저 수집 후 출력 | 전위 순회로 방문 즉시 스트리밍 출력 | 임시 저장 공간 없이 순회와 동시에 출력 가능 |
| 정성 | "트리에서 어디부터 접근할지 불명확" | 순회 패턴(부모 먼저/자식 먼저/정렬)으로 문제 분류 | 트리 문제 해결 절차의 체계화 |

> 요약: 순회 방식을 문제 요구(부모 우선·정렬 순서·자식 우선)에 맞춰 선택하면 별도의 정렬·임시 저장 없이 O(N) 안에 처리 가능하다.

### 미래 전망
- **병렬 트리 순회**: 멀티코어·GPU 환경에서 서로 다른 서브트리를 독립 스레드로 동시에 순회하여 처리 시간을 단축하는 기법으로, MapReduce의 트리 처리 패턴이 대표적임.
- **영속 트리(Persistent Tree)와 순회**: 함수형 프로그래밍에서 이전 버전을 유지하는 트리의 순회는 상태 이력 추적·시간 여행 디버깅의 기반으로 활용됨.

### 👶 어린이를 위한 3줄 비유 설명

1. 가족 사진을 찍을 때 — 전위는 "아빠 먼저, 그다음 왼쪽 아이, 오른쪽 아이", 중위는 "왼쪽 아이, 아빠, 오른쪽 아이"(키 순서!), 후위는 "아이들 먼저, 아빠 마지막"이에요.
2. BST(이진 탐색 트리)에서 "왼쪽 아이 → 아빠 → 오른쪽 아이" 순서(중위)로 읽으면 숫자가 작은 것부터 큰 것 순으로 나와요!
3. 폴더 크기를 알려면 하위 폴더부터 세야 하니까 후위 순회예요. "내 폴더 크기 = 왼쪽 폴더 크기 + 오른쪽 폴더 크기 + 내 파일 크기"예요.
