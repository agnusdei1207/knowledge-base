# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 이진 트리의 모든 노드를 중복 없이 한 번씩 방문하는 규칙적인 방법.
- **분류**: 
  - **깊이 우선 순회 (DFS)**: 전위(Pre-), 중위(In-), 후위(Post-order)
  - **너비 우선 순회 (BFS)**: 레벨 순회(Level-order)
- **핵심 직관**: "뿌리(Root) 노드를 언제 방문하느냐에 따라 이름과 용도가 결정된다."

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **전위 순회 (Preorder)** | **Root** -> Left -> Right | 부모가 먼저 모범을 보임 (복제) |
| **중위 순회 (Inorder)** | Left -> **Root** -> Right | 왼쪽 보고 나 보고 오른쪽 봄 (정렬) |
| **후위 순회 (Postorder)** | Left -> Right -> **Root** | 자식들 다 챙기고 나중에 나옴 (삭제) |
| **레벨 순회 (Level-order)** | 층별로 좌측에서 우측 순 방문 | 아파트 층별로 호수 돌기 (최단 거리) |
| **콜 스택 (Call Stack)** | 재귀 순회 시 되돌아올 주소를 저장 | 헨젤과 그레텔의 조약돌 |

## 깊이 이해

- **왜 3가지나 필요한가? (용도의 차이)**:
  1. **전위**: 트리를 복사하거나 구조를 직렬화(Serialization)할 때 유용. (부모가 있어야 자식을 만드니까)
  2. **중위**: **이진 탐색 트리(BST)**에서 중위 순회를 하면 데이터가 **오름차순**으로 예쁘게 정렬되어 나옴.
  3. **후위**: 트리 삭제(자식을 먼저 지워야 부모를 지움)나 수식 트리(Expression Tree) 계산(자식 피연산자를 먼저 구해야 부모 연산 가능)에 필수.

- **재귀 vs 반복 (Space Complexity)**:
  - **재귀(Recursion)**: 코드가 간결하지만 트리 높이($H$)만큼 스택 메모리를 소모함. (최악 $O(N)$)
  - **반복(Iterative)**: 명시적 스택(DFS)이나 큐(BFS)를 사용. 제어는 복잡하지만 스택 오버플로 위험이 적음.
  - **Morris Traversal**: 노드의 Null 포인터를 활용해 **공간 복잡도 $O(1)$**로 순회하는 고난도 기법.

- **수식 트리의 변환 (Infix to Postfix)**:
  - 중위 표기법: `(A + B) * C` (사람 중심)
  - 후위 표기법: `A B + C *` (컴퓨터 스택 계산 중심)
  - 후위 순회는 컴퓨터가 수식을 계산하는 가장 효율적인 논리 구조를 제공합니다.

- **일상 비유 (가족 여행)**:
  - **전위**: 아빠가 앞장서고 아이들이 따라감 (가이드형)
  - **중위**: 첫째 아이, 아빠, 둘째 아이 순으로 손잡고 감 (질서형)
  - **후위**: 아이들 다 차에 태우고 아빠가 마지막에 탐 (보호형)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 비선형 트리 구조에 **방문 순서(Ordering)**를 부여하여 선형적인 처리 흐름을 만드는 알고리즘임.
> 2. **가치**: 방식에 따라 **구조 복제(전위), 정렬 출력(중위), 하향식 집계(후위)** 등 서로 다른 비즈니스 로직을 완결함.
> 3. **판단 포인트**: 이진 탐색 트리(BST)와의 결합 시 **중위 순회는 $O(N)$ 정렬 도구**로 기능하며, 수식 계산에서는 후위 순회가 필수적임.

## Ⅰ. 트리 데이터의 선형적 흐름, 트리 순회의 개요
### 1. 정의
- 트리의 각 노드를 체계적인 방법으로 빠짐없이 한 번씩 방문하는 과정.
### 2. 순회의 필요성
- 비선형 구조인 트리를 선형적으로 나열하여 검색, 출력, 저장(Serialization)하기 위함.

## Ⅱ. 이진 트리 순회의 주요 유형 및 메커니즘
### 1. 깊이 우선 순회 (DFS 계열)
| 유형 | 순서 (Root/L/R) | 주요 용도 | 비고 |
|:---:|:---|:---|:---|
| **전위 (Preorder)** | **Root** $\rightarrow$ L $\rightarrow$ R | 트리 복사, 전위 표기법 변환 | 구조적 선행 처리 |
| **중위 (Inorder)** | L $\rightarrow$ **Root** $\rightarrow$ R | **BST 오름차순 정렬**, 수식 표현 | 논리적 순차 처리 |
| **후위 (Postorder)** | L $\rightarrow$ R $\rightarrow$ **Root** | 트리 삭제, 후위 표기법(Stack) | 결과적 집계 처리 |

### 2. 너비 우선 순회 (BFS 계열)
- **레벨 순회 (Level-order)**: 루트부터 깊이순으로 방문. 큐(Queue)를 사용하여 구현하며, 최단 경로 탐색의 기초가 됨.

## Ⅲ. 순회 방식별 알고리즘 상세 분석
### 1. 재귀적 순회 (Recursive Traversal)
- 분할 정복 기반으로 구현이 매우 간결함.
- 공간 복잡도: $O(H)$ (트리 높이만큼의 시스템 스택 사용).
### 2. 반복적 순회 (Iterative Traversal)
- 명시적 자료구조(Stack, Queue) 사용. 재귀 깊이 제한이 있는 환경에서 안정적.
### 3. 스레드 이진 트리 (Threaded Binary Tree)
- 노드의 Null 포인터를 활용하여 순회 속도를 높이고 스택 없이도 순회 가능하게 만든 구조.

## Ⅳ. 순회 기법의 실무 응용 사례
### 1. 컴파일러 및 인터프리터
- 추상 구문 트리(AST)를 전위 순회하여 중간 코드를 생성하거나, 후위 순회하여 연산 수행.
### 2. 파일 시스템 용량 계산
- 디렉토리(부모)의 크기는 하위 파일(자식)들의 크기 합이므로 반드시 **후위 순회**로 계산.
### 3. 데이터베이스 정렬
- 인덱스(B-Tree) 구조를 중위 순회하여 정렬된 결과셋(Result Set) 반환.

## Ⅴ. 기술사 관점의 성능 최적화 및 유의사항
### 1. 공간 효율성 극대화 (Morris Traversal)
- 스택이나 재귀 없이 $O(1)$ 공간으로 중위 순회를 수행하는 기법. 포인터를 잠시 수정했다가 복구하는 방식 사용.
### 2. 편향 트리(Skewed Tree) 대응
- 트리가 한쪽으로 치우칠 경우 재귀 순회는 $O(N)$의 스택을 소모하여 **Stack Overflow** 유발. 자가 균형 트리(AVL, RB)와 병행 필수.

## Ⅵ. 기술사 관점의 결론: "순서가 의미를 결정한다"
- 트리 순회는 단순한 노드 방문을 넘어, **데이터 간의 의존 관계와 처리 우선순위**를 정의하는 논리적 설계의 기초임.
- 고성능 아키텍트는 트리 구조의 특성과 비즈니스 목적에 최적화된 순회 방식을 선정하고, **메모리 제약(Stack Size)** 및 **데이터 분포(Skewness)**를 고려하여 견고한 순회 엔진을 구축해야 함.
