## 미리 알고가기

- **방문($Visit$)**: 노드에 접근하여 데이터를 처리(출력, 수정 등)하는 행위임
- **재귀($Recursion$)**: 함수가 자기 자신을 호출하여 서브트리 단위로 동일 로직을 반복 적용하는 방식임
- **직렬화($Serialization$)**: 트리 구조를 파일 저장이나 네트워크 전송을 위해 선형 데이터로 변환하는 과정임

## Ⅰ. 개요

- **통합 정의**: 이진트리의 모든 노드를 한 번씩 방문하되, 루트 노드의 처리 시점에 따라 비선형 계층 구조를 선형 순서로 변환하는 알고리즘 군임
- **개별 정의**:
  - **전위 순회 ($Pre-order$)**: 루트 $\rightarrow$ 좌 $\rightarrow$ 우 순서로 방문하며, 트리의 구조를 복사하거나 상단부터 처리할 때 사용함
  - **중위 순회 ($In-order$)**: 좌 $\rightarrow$ 루트 $\rightarrow$ 우 순서로 방문하며, 이진 탐색 트리($BST$)에서 정렬된 결과를 얻을 때 사용함
  - **후위 순회 ($Post-order$)**: 좌 $\rightarrow$ 우 $\rightarrow$ 루트 순서로 방문하며, 하위 자식을 먼저 처리해야 하는 삭제나 수식 계산에 사용함
- **배경/필요성**: 동일 트리라도 방문 시점에 따라 정렬, 복원, 해제 결과가 상이함. 목적에 부합하는 순회 전략 선택은 시스템의 논리적 정합성과 자원 관리 효율성에 직결됨

## Ⅱ. 특징 및 비교

### 가. 순회 방식별 상세 비교

| 비교 항목 | 전위 순회 ($Pre-order$) | 중위 순회 ($In-order$) | 후위 순회 ($Post-order$) |
|:---|:---|:---|:---|
| **처리 순서** | **루트** $\rightarrow$ 좌 $\rightarrow$ 우 | 좌 $\rightarrow$ **루트** $\rightarrow$ 우 | 좌 $\rightarrow$ 우 $\rightarrow$ **루트** |
| **핵심 용도** | 트리 복사, 직렬화, 디렉토리 구조 | $BST$ 정렬 출력, 데이터 탐색 | 노드 삭제, 수식 평가, 공간 계산 |
| **복잡도** | $O(n)$ ($n$: 노드 수) | $O(n)$ | $O(n)$ |
| **PPA 관점** | 초기 진입 속도 빠름 | 정렬 비용 최적화 | 자원 해제 안전성 확보 |

> 요약: 루트를 처음에 두면 전위, 중간에 두면 중위, 마지막에 두면 후위 순회로 구분함.

### 나. 기술적 통찰 (Architecture Insight)

1. **상향식 vs 하향식 처리**: 전위 순회는 부모의 정보를 자식에게 전달하는 하향식($Top-down$) 처리에 적합하고, 후위 순회는 자식의 계산 결과를 부모에게 보고하는 상향식($Bottom-up$) 집계에 최적화됨
2. **공간 효율성 ($Call$ $Stack$)**: 재귀적 순회의 공간복잡도는 트리 높이 $h$에 비례하는 $O(h)$임. 균형 트리($\log n$)와 편향 트리($n$)의 높이 차이에 따른 스택 오버헤드 관리가 필수적임
3. **구조 복원력**: 단일 순회 결과는 유일한 트리 복원이 불가함. 전위+중위 또는 후위+중위 조합을 통해 구조적 무결성을 재구성할 수 있음

## Ⅲ. 구성요소 및 알고리즘 구조

### 가. 순회 구성요소

| 구성요소 | 역할 및 정의 | 핵심 포인트 |
|:---|:---|:---|
| **루트 ($Root$)** | 현재 방문 중인 기준 노드 | 처리 시점(Pre/In/Post) 결정 |
| **좌·우 서브트리** | 재귀 호출의 대상이 되는 부분 트리 | 분할 정복 모델의 기본 단위 |
| **콜 스택 ($Stack$)** | 복귀 경로 및 상태를 저장하는 메모리 | 재귀 깊이($Depth$)에 따른 자원 관리 대상 |

### 나. 알고리즘 동작 원리 (재귀 구조)

```text
Function Traverse(Node T):
  If T is Null: Return
  1. Process(T) [Pre-order 시점]
  2. Traverse(T.Left)
  3. Process(T) [In-order 시점]
  4. Traverse(T.Right)
  5. Process(T) [Post-order 시점]
```

## Ⅳ. Real-world Troubleshooting

1. **재귀 깊이 초과 ($Stack$ $Overflow$)**
   - **문제**: 편향 트리에서 $n$이 클 경우 시스템 콜 스택 한계를 초과하여 프로세스 비정상 종료
   - **대응**: 명시적 스택 자료구조를 활용한 **반복문 순회($Iterative$ $Traversal$)**로 전환하여 스택 공간을 제어함

2. **순회 전략 오적용에 따른 데이터 오염**
   - **문제**: 하위 자원을 먼저 해제해야 하는 상황에서 전위 순회를 적용하여 끊긴 포인터($Dangling$ $Pointer$) 발생
   - **대응**: 의존성 관계가 있는 작업은 반드시 **후위 순회**를 강제하고, $Unit$ $Test$로 처리 순서를 검증함

3. **비선형 데이터의 직렬화 모호성**
   - **문제**: 선형화된 데이터만으로 원래의 트리 구조 복원이 불가능하여 데이터 전송 후 정합성 깨짐
   - **대응**: $Null$ 마커를 포함한 전위 순회나, 두 가지 이상의 순회 결과를 쌍으로 저장하는 프로토콜을 설계함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **컴파일러 엔진** | 추상 구문 트리($AST$) 후위 순회 | 연산 우선순위 정합성, 기계어 생성 효율 |
| **DB 쿼리 최적화** | 인덱스($B-Tree$) 중위 순회 | 데이터 정렬 정확도, 범위 검색 $Latency$ |
| **파일 시스템** | 디렉토리 크기 합산(후위), 복사(전위) | $Disk$ $Usage$ 정확도, 복사 완료 시간 |
| **가비지 컬렉션** | 객체 참조 그래프 순회 | 도달 불가능 객체($Unreachable$) 식별 정확도 |

## Ⅵ. 결론

이진트리 순회는 비선형 계층 데이터를 선형적으로 처리하기 위한 가장 기본적이면서도 강력한 아키텍처적 도구임. 기술사는 단순히 방문 순서를 암기하는 수준을 넘어, 워크로드의 의존성 관계를 분석하여 최적의 순회 전략을 도출하고 대규모 데이터 환경에서의 스택 가용성을 제어할 수 있어야 함.

특히 마이크로서비스 간 데이터 교환 시 트리 구조의 직렬화/역직렬화 과정에서 정보 손실을 방어할 수 있는 메타데이터 설계 역량이 요구됨. 결국 순회는 데이터의 연결성을 보존하며 흐름을 제어하는 핵심 기술이며, 이는 복잡한 시스템의 상태 관리와 자원 최적화의 기반이 됨.
