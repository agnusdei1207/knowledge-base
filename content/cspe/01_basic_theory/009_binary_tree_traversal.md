## Ⅰ. 개요

- **정의**: 이진트리 순회는 트리의 모든 노드를 정확히 한 번씩, 정해진 규칙에 따라 방문하는 절차임.
- **배경/필요성**: 트리는 배열·연결 리스트와 달리 정해진 나열 순서가 없는 비선형 구조이므로, 모든 노드를 누락 없이 처리하려면 부모를 자식보다 먼저·중간·나중에 방문할지를 규칙으로 먼저 정해야 함. 이 방문 시점 차이가 전위·중위·후위·레벨 순회를 가름.
- **출제 의도**: 순회 종류별 방문 규칙과 활용처를 구분하는 능력, 순회 조합에 따른 트리 복원 가능 여부 판단, 구현 방식(재귀·반복·Morris)별 공간복잡도 트레이드오프 이해를 확인함.
- **답안 방향**: 정의 → 순회별 규칙·활용 구분(Ⅱ) → 방문 시점 실행 절차(Ⅲ) → 중위·후위 심화 비교 및 구현 판단(Ⅴ) → 적용·결론(Ⅵ) 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 순회 규칙과 활용 구분 능력 확인 | 전위·중위·후위·레벨의 방문 순서 차이, 중위 순회의 BST 정렬 출력 성질 | 순회 종류 나열만 하고 활용 근거 누락 |
| 순회 조합에 따른 트리 복원 가능 여부 판단 | 전위+중위·후위+중위는 복원 가능, 전위+후위는 일반 이진트리에서 복원 불가 | 모든 순회 조합이 복원 가능하다고 단정 |
| 구현 방식별 공간복잡도 트레이드오프 이해 | 재귀·반복은 O(H), Morris Traversal은 O(1) | 세 구현의 시간복잡도까지 다르다고 혼동 |

> 요약: 순회 문제는 "부모를 언제 방문하는가"와 "그 결과를 어떤 자료구조로 구현하는가" 두 축을 함께 짚어야 함.

## Ⅱ. 구조 및 구성요소

```text
노드 방문 시점 구조

        부모(N)
        /    \
     좌(L)   우(R)

전위: N -> L -> R   (부모 먼저)
중위: L -> N -> R   (부모 중간)
후위: L -> R -> N   (부모 나중)
레벨: 0층 -> 1층 -> 2층 ...(큐 기반, BFS 일반론은 010 참조)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 전위 순회 (Pre-order) | 부모→좌→우 순서로 방문, 부모를 가장 먼저 처리 | 트리 복제·직렬화 시 부모 노드를 먼저 생성 |
| 중위 순회 (In-order) | 좌→부모→우 순서로 방문 | BST에서는 오름차순 정렬 결과를 그대로 산출 |
| 후위 순회 (Post-order) | 좌→우→부모 순서로 방문, 부모를 가장 나중에 처리 | 자식 결과를 먼저 확보해야 하는 높이 계산·하위 구조 삭제에 대응 |
| 레벨 순회 (Level-order) | 같은 깊이의 노드를 큐로 층별 방문 | BFS 층별 탐색과 동일 원리(010 참조) |
| 중위 선행자 (Inorder Predecessor) | 기준 노드 바로 앞에 중위 방문되는 노드, 좌측 서브트리의 최우측 노드 | 줄 서기에서 내 바로 앞사람 |
| Morris Traversal | 중위 선행자에 임시 스레드를 연결해 재귀·스택 없이 순회 | 갈림길에 표식을 남기고 돌아온 뒤 표식을 지우는 방식 |

> 요약: 순회 종류는 부모 방문 시점(먼저/중간/나중/층별)으로 구분되며, 중위 선행자와 Morris Traversal은 그 방문 순서를 추가 메모리 없이 구현하기 위한 장치임.

## Ⅲ. 동작원리 및 흐름도

```text
예시 트리:
        (1)
       /   \
     (2)   (3)
     / \     \
   (4) (5)   (6)

전위(부→좌→우): 1 -> 2 -> 4 -> 5 -> 3 -> 6
중위(좌→부→우): 4 -> 2 -> 5 -> 1 -> 3 -> 6
후위(좌→우→부): 4 -> 5 -> 2 -> 6 -> 3 -> 1
레벨(층별, BFS): 1 -> 2 -> 3 -> 4 -> 5 -> 6
```

- 1단계: 순회 규칙을 먼저 결정함 — 부모 방문 시점을 좌·우 서브트리 처리 순서 중 어디에 둘지(전위=먼저, 중위=중간, 후위=나중, 레벨=층별 큐) 정함.
- 2단계: 좌측 서브트리를 정의된 규칙으로 재귀 처리함 — 전위는 이 단계 전에 부모를 이미 방문했고, 중위·후위는 부모 방문을 이 단계 뒤로 보류함.
- 3단계: 규칙에서 정한 시점(좌 이전/좌 이후 우 이전/좌우 이후)에 도달하면 부모 노드를 방문·처리함.
- 4단계: 우측 서브트리를 동일 규칙으로 재귀 처리한 뒤 모든 노드 방문이 끝나면 종료함(레벨 순회는 큐가 비면 종료).

> 요약: 예시 트리 하나에서도 부모 방문 시점만 바꾸면 전위·중위·후위·레벨 네 가지 서로 다른 방문 순서가 산출됨.

## Ⅳ. 특징

- 재귀 구현은 호출 깊이가 트리 높이 H에 비례해 O(H) 콜스택을 소비함(재귀·스택 메커니즘 자체는 007 참조).
- Morris Traversal은 중위 선행자에 임시 스레드를 연결해 O(1) 공간으로 순회를 완료하고, 순회 중 변경한 포인터는 즉시 원복하되 순회 도중 트리 구조가 일시 변경되므로 멀티스레드 동시 접근 환경에는 부적합함.
- 전위·중위·후위 모두 각 노드를 정확히 한 번 방문하므로 시간복잡도는 O(N)으로 동일함.
- 전위+후위 조합만으로는 일반 이진트리 복원이 불가능함 — 좌우 서브트리 경계를 나눌 중위 정보가 없으며, 완전 이진트리(모든 노드의 자식이 0개 또는 2개)에서만 유일하게 복원 가능함.

> 요약: 세 순회의 결과는 방문 시점 차이에서 나오고, 구현 방식(재귀/반복/Morris)의 차이는 공간복잡도에서만 갈림.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 중위 순회 | 후위 순회 | 선택 기준 |
|:---|:---|:---|:---|
| 부모 방문 시점 | 좌 서브트리 완료 후, 우 서브트리 전 | 좌·우 서브트리 모두 완료 후 | 자식 처리 결과가 필요한 시점에 따라 결정 |
| 대표 활용 | BST 정렬 출력, 범위 스캔 | 트리 높이 계산, 하위 구조 선삭제, 후위 표기 수식 평가 | "정렬 순서가 필요한가" vs "자식 결과를 먼저 집계해야 하는가" |
| 복원 시 루트 정보 | 좌우 서브트리 분할 기준점(단독으로는 루트 특정 불가) | 결과 맨 끝이 루트(단독으로는 좌우 경계 특정 불가) | 두 순회를 함께 확보해야 트리 복원 가능 |

> 요약: 중위는 "정렬"과 "분할 기준", 후위는 "자식 우선 집계"와 "루트 위치"를 담당하며, 트리 복원은 이 둘의 조합이 있어야 성립함.

**리스크·대응 (불릿):**
- 편향 트리에서 재귀 순회 시 재귀 깊이가 노드 수 N에 근접해 스택 오버플로우 발생 가능 → 반복(명시적 스택) 또는 Morris Traversal로 전환(지표: 최대 재귀 깊이).
- 전위+후위 조합만으로 트리 복원 시도 시 좌우 서브트리 경계 판별 실패 가능 → 중위 순회 결과를 반드시 함께 확보(지표: 복원 결과와 원본 트리 일치 여부 검증).

**도입 후 점검 지표 (불릿):**
- 처리 성능: 순회 1회 소요 시간이 노드 수 대비 O(N)에서 벗어나는지 측정.
- 메모리: 재귀·반복 방식은 최대 스택 깊이, Morris Traversal은 순회 종료 후 임시 스레드 잔존 여부(원본 트리 복원 확인).

## Ⅵ. 실무 적용 및 결론

1. 단기: 문제 요구(정렬 출력·자식 결과 선집계·부모 선생성)를 판별해 적합한 순회부터 선정함.
2. 중기: 트리 높이가 큰 데이터를 다루는 시스템은 재귀 대신 반복 또는 Morris Traversal로 전환해 스택 오버플로우 위험을 제거함.
3. 장기: 트리 재구성·직렬화가 필요한 시스템은 중위 순회 결과를 항상 함께 보존하도록 설계함.

- 기술사적 판단: 순회 방식 선택은 "부모를 언제 방문해야 문제가 요구하는 결과가 나오는가"를 먼저 판별한 뒤, 재귀·반복·Morris 중 공간 제약에 맞는 구현 방식을 고르는 2단계 판단임.
- 기술사 제언: 임베디드·대용량 트리처럼 메모리 제약이 큰 환경은 Morris Traversal 도입을 우선 검토함.
