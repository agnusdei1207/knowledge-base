## Ⅰ. 개요
- **정의**: 이진트리의 모든 노드를 특정 규칙에 따라 한 번씩 방문하는 체계적 탐색 방법
- **배경/필요성**: 트리는 비선형 구조이므로 노드 방문 순서가 자명하지 않아, 목적에 맞는 순회 규칙이 필요함
- **비유**: 건물 점검 — 층별로 돌지(레벨), 한 라인을 끝까지 내려갔다 올지(깊이) 선택하는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 4가지 순회 방식의 방문 순서 차이 | 전위(Root-L-R), 중위(L-Root-R), 후위(L-R-Root), 레벨(BFS) | 재귀 vs 스택 반복 구현 방식을 구분할 것 |

> 요약: 전위·중위·후위·레벨 순회로 비선형 트리를 체계적으로 탐색하는 방법임

## Ⅱ. 구성요소
```text
          [A]              전위: A-B-D-E-C-F
         /   \             중위: D-B-E-A-C-F
       [B]   [C]           후위: D-E-B-F-C-A
      /   \     \          레벨: A-B-C-D-E-F
    [D]   [E]   [F]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 전위 순회(Pre-order) | Root → Left → Right 순서로 방문하여 트리 복제·직렬화에 활용 | 책 목차 — 장 제목을 먼저 읽고 하위 절로 진입 |
| 중위 순회(In-order) | Left → Root → Right 순서로 방문하여 BST에서 정렬 결과를 산출 | 왼쪽부터 차례로 읽는 가로 읽기 |
| 후위 순회(Post-order) | Left → Right → Root 순서로 방문하여 하위 노드 처리 후 상위를 처리 | 폴더 삭제 — 하위 파일 먼저 삭제 후 폴더 삭제 |
| 레벨 순회(Level-order) | 큐(007 참조)를 사용하여 같은 깊이의 노드를 좌→우 순서로 방문 | 건물 층별 점검 — 1층부터 한 층씩 탐색 |
| 재귀/스택 | 깊이 우선 순회의 구현 방식 — 재귀(콜스택 활용) 또는 명시적 스택(007 참조) 사용 | 메모장 vs 기억력 — 적어두고 되돌아가기 vs 머리로 기억 |

> 요약: 방문 순서(Root 위치)에 따라 전위·중위·후위로 나뉘고, 레벨 순회는 BFS 방식으로 수행함

## Ⅲ. 절차
```text
  루트 시작           순회 규칙 적용       하위 트리 재귀        결과 수집
  (현재 노드 설정)   (방문 순서 결정)     (Left/Right 진입)    (방문 순서 기록)
       |                  |                   |                   |
       +---노드 확인------>+---규칙 분기------->+---재귀/큐 처리---->+
     NULL 여부 검사     Pre/In/Post/Level    서브트리 반복 탐색   방문 리스트 완성
```
- 1단계: 루트 노드에서 시작하여 현재 노드가 NULL인지 검사함
- 2단계: 순회 종류에 따라 Root 방문 시점(전/중/후) 또는 큐 삽입(레벨)을 결정함
- 3단계: 좌측·우측 서브트리에 대해 재귀 호출하거나 큐에서 꺼내며 하위 노드를 처리함
- 4단계: 각 노드의 방문 결과를 순서대로 수집하여 최종 순회 결과를 반환함

> 요약: 루트 시작 → 규칙 적용 → 서브트리 재귀 → 결과 수집의 4단계로 전체 노드를 순회함

## Ⅳ. 문제점
- 재귀 스택 오버플로: 트리 높이가 깊으면 콜스택이 한계에 도달하여 런타임 오류 발생 — 편향 트리(008 참조)에서 높이 n만큼 스택 프레임 소모
- 순회 방식 혼동: 전위·중위·후위의 Root 방문 시점을 잘못 적용하면 결과가 달라짐 — 수식 트리 평가 시 오류로 이어짐
- 레벨 순회 메모리: 최하위 레벨 노드 수(최대 n/2)만큼 큐 공간 필요 — 완전 이진트리에서 메모리 사용량이 급증함

> 요약: 재귀 스택 한계, 순회 방식 혼동, 레벨 순회 큐 메모리가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 명시적 스택을 사용한 반복(Iterative) 구현으로 콜스택 오버플로 방지
2. 중기: 순회 종류별 방문 시점(Root 처리 위치)을 명확히 문서화하여 구현 오류 예방
3. 장기: Morris Traversal(스레드 이진트리 활용)로 O(1) 추가 공간에서 중위 순회 수행

> 요약: 반복 구현 → 규칙 명세화 → Morris Traversal로 스택·혼동·메모리 문제를 해소함

## Ⅵ. 전망
- 발전 방향: 병렬 트리 순회(서브트리 단위 분할 처리)로 대규모 트리 탐색 시간 단축
- 기술사적 판단: 순회 방식 선택이 컴파일러(수식 파싱), DB(인덱스 스캔), 파일시스템(디렉터리 탐색)의 성능을 좌우함
- 기술사 제언: 트리 높이와 메모리 제약을 사전 분석하여 재귀·반복·Morris 중 적합한 구현 방식을 선정할 필요
