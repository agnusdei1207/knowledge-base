# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 이진 트리 순회는 **트리의 모든 노드를 빠짐없이 한 번씩 방문하는 규칙**으로, 뿌리(Root)를 언제 방문하느냐에 따라 전위(Pre)·중위(In)·후위(Post) 세 방식으로 나뉜다(트리·노드 개념은 008 참조).
- **왜 필요한가**: 트리는 배열처럼 인덱스 순서가 없는 비선형 구조라, "어떤 순서로 노드를 처리할지"를 정하지 않으면 출력·계산·복사 같은 작업을 할 수 없기 때문이다.
- **핵심 직관**: "왼쪽 서브트리 → 오른쪽 서브트리는 고정, **뿌리를 앞·가운데·뒤 중 어디서 찍느냐**만 다르다" — 이 한 가지 차이가 전위·중위·후위를 가른다.

## 핵심 용어 정리 (내부에 등장하는 것들)

세 순회의 차이는 "Root를 언제 방문하는가" 하나다. 관련 용어를 먼저 세운다(노드·서브트리·리프는 008에서 정의). 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 트리 순회 (상위 키워드) | 모든 노드를 규칙에 따라 한 번씩 방문 | 조직도 전원을 정해진 순서로 호명 |
| Root / Left / Right | 현재 노드 / 왼쪽 자식 서브트리 / 오른쪽 자식 서브트리 | 나 / 왼쪽 부하라인 / 오른쪽 부하라인 |
| 전위(Preorder) | Root → Left → Right (뿌리 먼저) | 상사부터 이름 부르고 부하로 내려감 |
| 중위(Inorder) | Left → Root → Right (뿌리 가운데) | 왼쪽 다 보고 나서 나, 그다음 오른쪽 |
| 후위(Postorder) | Left → Right → Root (뿌리 마지막) | 부하 다 처리하고 마지막에 상사 |
| 깊이 우선(DFS) | 한 갈래를 끝까지 내려간 뒤 되돌아오는 방식 | 미로 한 길 끝까지 갔다가 되돌아오기 |
| 너비 우선(BFS)·레벨 순회 | 같은 깊이를 좌→우로 훑고 다음 층 진행 | 건물을 층별로 훑기 |
| 재귀(Recursion) | 함수가 자신을 불러 서브트리를 같은 규칙으로 처리 | 러시아 인형 안에 같은 인형 |
| 콜 스택(Call Stack) | 재귀 호출이 쌓이는 메모리(트리 높이만큼) | 되돌아갈 지점을 쌓아 둔 접시탑 |

## 깊이 이해
- **배경·문제의식**: 비선형 트리에는 "다음 원소"라는 자연 순서가 없다. 노드를 처리하려면 방문 순서를 규칙으로 정해야 한다. 세 순회 모두 왼쪽→오른쪽 순서는 같고, **Root를 처리하는 시점**만 앞(전위)·중간(중위)·뒤(후위)로 옮긴 것이다.
- **작동 원리 (어떻게+왜)**:
  - 전위(Root-L-R): 부모를 먼저 찍으므로 **트리 구조 복제·직렬화**에 쓴다(부모를 먼저 만들어야 자식을 붙인다).
  - 중위(L-Root-R): 이진 탐색 트리(BST)에서 실행하면 **키가 오름차순으로 정렬 출력**된다 — 왼쪽(작은 값)→뿌리→오른쪽(큰 값) 순서 때문이다.
  - 후위(L-R-Root): 자식을 먼저 처리하므로 **트리 삭제·디렉터리 용량 합산·수식 계산**에 쓴다(자식 결과가 있어야 부모를 계산·해제한다).
  - 구현은 재귀가 자연스럽다. 재귀는 내부적으로 **콜 스택**을 쓰므로, 스택을 명시적으로 두면 반복문으로도 같은 순회를 만든다.
- **비유**: 회사 조직도 순회. 전위는 "상사 이름 먼저 부르고 부하로", 후위는 "부하 보고를 다 받은 뒤 상사가 결재"(용량 합산·해제와 같은 상향 집계).
- **구체 예시(수치·사례)**: 노드가 `2(왼) - 5(뿌리) - 8(오른)`인 BST에서 중위 순회는 2→5→8(오름차순), 전위는 5→2→8, 후위는 2→8→5다. 수식 트리 `(a+b)`를 후위로 읽으면 `a b +`(후위 표기법·스택 계산기 입력)가 된다. 세 순회 모두 모든 노드를 1번씩 보므로 시간은 O(N), 콜 스택 공간은 트리 높이에 비례한다(O(N)·O(log N) 의미는 001·002 참조).
- **흔한 오해·주의점**:
  - **중위 순회가 정렬되는 것은 BST일 때만이다.** 정렬 규칙이 없는 일반 이진 트리는 중위 결과가 정렬되지 않는다.
  - 재귀 순회의 공간은 O(N)이 아니라 **트리 높이 O(h)**다 — 균형 트리면 O(log N), 편향 트리면 O(N).
  - DFS 세 순회와 별개로 **BFS(레벨 순회)**는 큐(007)를 써 층별로 방문하는 다른 축의 방법이다.

## 연결 개념
- **트리 자료구조 (008)**: 순회의 대상인 노드·서브트리·BST 정렬 규칙을 정의한 상위 개념.
- **스택·큐 (007)**: 반복형 DFS는 스택, BFS 레벨 순회는 큐를 뼈대로 사용.
- **분할 정복·재귀 (014)**: 서브트리를 같은 규칙으로 나눠 푸는 재귀 순회의 사고 틀.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진 트리 순회는 Left→Right 순서를 고정하고 Root 방문 시점만 앞·중간·뒤로 바꾼 세 가지 노드 방문 규칙임.
> 2. **가치**: 비선형 트리에 처리 순서를 부여해 복제(전위)·정렬 출력(중위)·집계·해제(후위)를 각각 가능케 함.
> 3. **판단 포인트**: 목적이 구조 복제면 전위, 정렬이면 중위(BST), 상향 집계·삭제면 후위를 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세 순회 규칙 구분 | Root 방문 시점 차이(전·중·후위) | 좌우 순서가 방식마다 다르다고 오기 |
| 순회별 용도 이해 | 복제·정렬·집계 목적 매핑 | 중위 정렬을 일반 트리에도 적용 단정 |
| 구현·복잡도 파악 | 재귀·스택 구현과 시간 O(N)·공간 O(h) | 공간을 O(N)으로 뭉뚱그려 높이 누락 |

> 요약: Root 시점 차이로 세 순회를 구분하고, 용도 매핑과 재귀·스택 구현·복잡도(O(N)·O(h))를 함께 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 이진 트리의 모든 노드를 Root 방문 시점 규칙에 따라 한 번씩 방문하는 방법임
- 배경: 트리는 인덱스 순서가 없는 비선형 구조라 처리 순서를 규칙으로 정해야 함
- 필요성: 트리 복제·정렬 출력·용량 집계·삭제 등 작업마다 요구되는 방문 순서가 달라 세 순회가 필요함

## Ⅱ. 구조 및 구성요소
선형 구조도 (Root 방문 시점):

    공통 축 : Left(왼쪽 서브트리) ... Right(오른쪽 서브트리)  [순서 고정]
      / 전위(Pre)  : Root -> Left -> Right   (뿌리 먼저)
      / 중위(In)   : Left -> Root -> Right   (뿌리 가운데)
      / 후위(Post) : Left -> Right -> Root   (뿌리 마지막)
    별도 축 : BFS(레벨 순회) = 큐로 같은 깊이를 좌->우 방문

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Root 방문 시점 | 전·중·후위를 가르는 유일한 변수 | 좌우 순서는 항상 왼쪽 먼저 |
| 재귀 호출 | 서브트리를 동일 규칙으로 반복 처리 | 콜 스택이 트리 높이만큼 쌓임 |
| 명시적 스택 | 재귀 없이 반복형 DFS 순회 구현 | 재귀 깊이 한계 회피 |
| 큐(BFS용) | 레벨 순회의 다음 방문 노드 대기 | DFS 세 순회와 다른 축 |

> 요약: 좌우 순서는 고정이고 Root 방문 시점만 세 순회를 가르며, 재귀·스택은 DFS를, 큐는 BFS를 구현함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (재귀 중위 순회):

    노드 방문 -> 왼쪽 서브트리 재귀 -> 현재 Root 처리 -> 오른쪽 서브트리 재귀 -> 반환

1. 하강: 순회 함수가 현재 노드에서 규칙에 따라 왼쪽 자식으로 재귀 호출하며 내려감
2. Root 처리: 방식별 시점(전위=하강 전, 중위=왼쪽 복귀 후, 후위=양쪽 복귀 후)에 현재 노드를 방문·출력함
3. 복귀: 리프에 닿으면 콜 스택을 되짚어 부모로 돌아오며 미방문 서브트리로 이동함
4. 종료: 모든 노드를 한 번씩 방문하면 O(N) 시간에 순회가 끝남(콜 스택 공간은 높이 O(h))

> 요약: 왼쪽 하강과 콜 스택 복귀를 반복하되 Root 처리 시점만 달리해 세 순회를 구현하며 시간은 O(N)임.

## Ⅳ. 특징
- 시점 단일 변수: 좌우 순서는 고정이고 Root 방문 시점만으로 세 방식이 결정됨
- 선형 시간: 모든 노드를 1회씩 방문해 시간 복잡도가 O(N)으로 동일함
- 높이 비례 공간: 재귀 콜 스택이 트리 높이 O(h)만큼 필요(균형 log N, 편향 N)
- 목적별 전용성: 복제는 전위, 정렬은 중위(BST), 집계·삭제는 후위로 용도가 갈림
- 구현 이원성: 재귀와 명시적 스택으로 동일 순회를 구현 가능(반복형은 재귀 깊이 한계 회피)

## Ⅴ. 심화 비교 및 적용 판단

Root 방문 시점·정렬성·대표 용도 축에서 세 순회를 대조함(트리 종류 비교는 008 참조).

| 구분 | 전위(Preorder) | 중위(Inorder) | 후위(Postorder) |
|:---|:---|:---|:---|
| 방문 순서 | Root → Left → Right | Left → Root → Right | Left → Right → Root |
| Root 시점 | 하강 전(먼저) | 왼쪽 복귀 후(가운데) | 양쪽 복귀 후(마지막) |
| 정렬 출력 | 불가 | BST에서 오름차순 정렬 | 불가 |
| 대표 용도 | 트리 복제·직렬화(prefix) | 정렬·범위 출력 | 삭제·용량 집계·수식 계산(postfix) |

> 요약: 목적이 구조 복제면 전위, 정렬·구간 출력이면 중위(BST 한정), 상향 집계·해제면 후위가 적합함.

**리스크·대응:**
- 재귀 스택 오버플로 — 편향 트리에서 높이 N만큼 콜 스택 초과 → 명시적 스택 반복형·균형 트리(008) 사용
- 중위 정렬 오적용 — 비BST에 중위를 써 정렬로 오인 → 정렬 전제(BST 여부) 사전 확인
- 방문 누락·중복 — 좌우 재귀 순서 오류로 노드 누락 → 순회 후 방문 노드 수 = N 검증

**점검 지표:**
- 정확성: 방문 노드 수 = 전체 노드 수 N — 순회 결과 카운트 대조
- 효율: 최대 재귀 깊이 = 트리 높이 — 스택 사용량 프로파일링

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. XML·JSON·구문 트리(AST)를 전위 순회로 직렬화·복제해 파서·트랜스파일러의 구조 보존 처리 구현
2. BST 기반 정렬 컬렉션(008의 Red-Black 맵)을 중위 순회로 오름차순·범위 출력에 활용
3. 디렉터리 용량 합산·수식 트리 계산·트리 메모리 해제를 후위 순회로 자식 결과 집계 후 부모 처리

**결론:**
- 기술사 판단: 목적이 구조 보존·복제면 전위, 정렬·구간 조회면 중위(BST), 상향 집계·삭제면 후위를 택하는 조건부 선택이 유효함
- 향후 방향: 대규모·병렬 환경에서 재귀 깊이 한계를 피하는 반복형·병렬 트리 순회가 컴파일러·질의 엔진 최적화의 과제로 대두됨
