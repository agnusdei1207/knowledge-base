## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진트리 순회(Binary Tree Traversal)는 트리의 모든 노드를 **정확히 한 번씩** 방문하는 체계적 방법이다. 부모·왼쪽·오른쪽 자식을 방문하는 상대적 순서에 따라 전위(Pre-order: 부→좌→우), 중위(In-order: 좌→부→우), 후위(Post-order: 좌→우→부)로 나뉜다.
> 2. **가치**: 중위 순회는 BST의 원소를 **정렬 순서**로 방문하고, 후위 순회는 **디렉토리 크기 계산**이나 **수식 트리 평가**처럼 자식을 먼저 처리해야 하는 문제에 사용된다. 전위 순회는 트리 **복제**와 **직렬화**에 사용된다. 순회 방식의 선택이 곧 문제 해결 전략이다.
> 3. **융합**: 컴파일러의 구문 트리(AST) 처리, 파일 시스템의 디렉토리 크기 계산(후위), 데이터베이스 인덱스의 범위 스캔(중위), XML/JSON 파싱(전위) 등 트리를 다루는 모든 분야에서 순회 패턴이 핵심이다.

## 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| 전위 순회 (Pre-order) | 부모 → 왼쪽 → 오른쪽 순서로 방문하는 트리 순회 방식 | 대장이 먼저 출발하고 부하들이 따라가는 선발대 탐색 |
| 중위 순회 (In-order) | 왼쪽 → 부모 → 오른쪽 순서로 방문하며, BST에서는 정렬 순서를 출력 | 사전에서 가나다순(작은 것→큰 것)으로 읽는 것 |
| 후위 순회 (Post-order) | 왼쪽 → 오른쪽 → 부모 순서로 방문하며, 자식을 먼저 처리해야 하는 문제에 적합 | 부하들이 일을 다 끝낸 후 대장이 최종 결산하는 순서 |
| 레벨 순회 (Level-order) | BFS 방식으로 같은 깊이의 노드를 왼쪽에서 오른쪽으로 층별 방문 | 건물을 1층부터 꼭대기까지 한 층씩 올라가며 방 검사 |
| Morris Traversal | 스레디드 링크를 임시 생성하여 $O(1)$ 공간에서 순회하는 기법 | 미로 바닥에 화살표를 그려놓고 나중에 지우는 공간 절약 탐색법 |
| 파스 트리 (Parse Tree) | 유도 과정을 트리로 시각화한 구조로, 순회의 대상 | 문장의 문법 구조를 가계도처럼 펼쳐놓은 나무 |

## Ⅰ. 개요 및 필요성

- **개념**: 트리 순회는 재귀적으로 정의된다. 전위(Preorder)는 `visit(node) → traverse(left) → traverse(right)`, 중위(Inorder)는 `traverse(left) → visit(node) → traverse(right)`, 후위(Postorder)는 `traverse(left) → traverse(right) → visit(node)`. 레벨 순회(Level-order)는 BFS로 같은 깊이의 노드를 왼→오 순서로 방문한다.

- **필요성**: 트리는 비선형(Non-linear) 자료구조이므로, 배열이나 연결 리스트처럼 순서대로 따라갈 수 없다. "어떤 순서로 방문할 것인가"를 정의해야 체계적으로 모든 노드를 처리할 수 있다. 이 순서의 선택이 문제에 따라 다르며, 잘못된 순회를 선택하면 정답을 구할 수 없다.

- **비유**: 트리 순회는 **미술관 관람 루트**와 같다. 전위는 "입구부터 왼쪽으로 쭉, 끝에서 오른쪽으로"(관장님 안내), 중위는 "작은 작품→큰 작품→더 큰 작품 순"(크기순 감상), 후위는 "구석부터 보고 마지막에 메인 작품"(청소부의 동선)이다.

- **등장 배경 및 발전 과정**:
  1. **1960년대**: Knuth가 "The Art of Computer Programming"에서 전위·중위·후위 순회를 체계적으로 정리하고, 순회 간의 상호 변환을 증명했다.
  2. **Morris Traversal (1979)**: Joseph Morris가 $O(1)$ 공간에서 중위 순회를 수행하는 기법을 발표. 스레디드 트리(Threaded Tree)의 아이디어를 확장한 것이다.
  3. **현대**: 순회는 직렬화(Serialization)의 기반이다. LeetCode 297번(이진 트리 직렬화)은 전위 순회 기반이며, 분산 시스템에서 트리 구조 데이터를 네트워크로 전송할 때 핵심이다.

```text
+-----------------------------------------------------------------------+
|         이진트리 순회 3종의 방문 순서 비교                            |
+-----------------------------------------------------------------------+
|                                                                       |
|  예시 트리:                                                           |
|              (1)                                                      |
|             /   \                                                    |
|           (2)   (3)                                                  |
|           / \     \                                                  |
|         (4) (5)   (6)                                                |
|                                                                       |
|  [전위 순회 — 부모 먼저 (Pre-order)]                                 |
|  visit → left → right                                               |
|  결과: 1 → 2 → 4 → 5 → 3 → 6                                       |
|  용도: 트리 복제, 직렬화, 수식의 폴란드 표기법                       |
|                                                                       |
|  [중위 순회 — 부모 중간 (In-order)]                                  |
|  left → visit → right                                               |
|  결과: 4 → 2 → 5 → 1 → 3 → 6                                       |
|  용도: BST의 오름차순 출력, 범위 쿼리, 인덱스 스캔                  |
|                                                                       |
|  [후위 순회 — 부모 마지막 (Post-order)]                              |
|  left → right → visit                                               |
|  결과: 4 → 5 → 2 → 6 → 3 → 1                                       |
|  용도: 트리 삭제, 디렉토리 크기 계산, 수식 평가                     |
|                                                                       |
|  [레벨 순회 — 층별 (Level-order/BFS)]                                |
|  같은 깊이를 왼→오 순서로                                            |
|  결과: 1 → 2 → 3 → 4 → 5 → 6                                       |
|  용도: 최단 경로, 이진 트리 프린팅, 직렬화                          |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 같은 트리에 대해 4가지 순회의 방문 순서가 모두 다르다. 핵심은 **부모 노드를 언제 방문하느냐**이다. 전위는 부모를 먼저(Pre) 방문하므로 루트 1이 첫 번째이다. 중위는 왼쪽을 먼저 다 본 후(In) 부모를 방문하므로 가장 왼쪽인 4가 첫 번째이다. BST에서 중위 순회를 하면 키가 오름차순으로 나온다는 것이 핵심 성질이다. 후위는 자식을 모두 처리한 후(Post) 부모를 방문하므로 루트 1이 마지막이다. 이는 "자식부터 처리해야 부모를 결정할 수 있는" 문제(디렉토리 크기 = 하위 파일 크기 합)에 적합하다.

- **📢 섹션 요약 비유**: 전위는 "대장이 먼저 출발"(부모 먼저), 중위는 "나이순으로 한 명씩"(정렬), 후위는 "막내부터 출발, 대장이 마지막"(자식 먼저)입니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 내부 동작 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **재귀 호출 스택** | 순회 상태 관리 | 현재 노드·방문 방향을 콜 스택에 저장 | 함수 호출 메커니즘 | 미로에서 갈림길마다 빵 부스러기 |
| **반복문 + 명시적 스택** | 재귀 없이 순회 | 스택에 노드를 push/pop하여 순서 제어 | 스택 오버플로우 방지 | 수동으로 빵 부스러기 놓기 |
| **Morris Traversal** | $O(1)$ 공간 순회 | 스레디드 링크를 임시로 생성하여 역방향 이동 | 메모리 극한 환경 | 실 한 가닥으로 미로 추적 |

### 재귀 vs 반복 구현 — 중위 순회

```text
+-----------------------------------------------------------------------+
|    중위 순회 — 재귀 구현 vs 반복(스택) 구현                          |
+-----------------------------------------------------------------------+
|                                                                       |
|  [재귀 구현]                      [반복(스택) 구현]                   |
|  +----------------------------+   +-------------------------------+   |
|  | def inorder(node):         |   | def inorder(root):            |   |
|  |   if node is None:         |   |   stack = []                  |   |
|  |     return                 |   |   curr = root                 |   |
|  |   inorder(node.left)       |   |   while curr or stack:        |   |
|  |   visit(node)              |   |     while curr:               |   |
|  |   inorder(node.right)      |   |       stack.append(curr)      |   |
|  +----------------------------+   |       curr = curr.left        |   |
|                                   |     curr = stack.pop()        |   |
|  시간: O(N)                       |     visit(curr)               |   |
|  공간: O(H) — 호출 스택           |     curr = curr.right         |   |
|  H = 트리 높이 (균형 시 log N,    +-------------------------------+   |
|       편향 시 N)                   시간: O(N)                         |
|                                    공간: O(H) — 명시적 스택          |
|  장점: 간결한 코드                 장점: 스택 오버플로우 안전         |
|  단점: 깊은 트리에서 스택오버플로우 단점: 코드 복잡도 증가            |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 재귀 구현은 3줄로 우아하지만, 트리 높이가 깊으면 시스템 콜 스택을 초과할 수 있다(Python 기본 재귀 제한 1,000). 반복 구현은 명시적 스택을 사용하여 이 문제를 피하며, 스택 크기를 동적으로 조절 가능하다. 두 구현 모두 시간 $O(N)$, 공간 $O(H)$이지만 실무에서는 반복 구현이 더 안전하다. Morris Traversal은 공간을 $O(1)$로 줄이지만, 트리 구조를 임시로 변경하므로 읽기 전용 트리에는 사용할 수 없다.

- **📢 섹션 요약 비유**: 재귀 순회는 "네비게이션이 알아서 길 안내"(편하지만 메모리 소모), 반복 순회는 "종이 지도를 직접 보며 갈림길 메모"(수동이지만 안전), Morris는 "길 바닥에 화살표를 그려놓고 나중에 지움"(공간 절약이지만 자국이 남음)입니다.

## Ⅲ. 비교 및 연결

### 비교 1: 순회 방식별 적합한 문제

| 문제 유형 | 적합한 순회 | 이유 |
|:---|:---|:---|
| BST 정렬 출력 | 중위(In-order) | 좌→부→우 = 오름차순 |
| 트리 복제/직렬화 | 전위(Pre-order) | 부모를 먼저 생성해야 자식을 연결 가능 |
| 트리 삭제 | 후위(Post-order) | 자식을 먼저 삭제해야 부모를 삭제 가능 |
| 수식 트리 평가 | 후위(Post-order) | 피연산자(리프)를 먼저 계산한 후 연산자(부모) 적용 |
| 최단 경로/최소 깊이 | 레벨(Level-order) | 층별 탐색으로 가장 먼저 발견된 경로가 최단 |
| 트리 높이 계산 | 후위(Post-order) | 좌우 자식 높이를 먼저 구한 후 max + 1 |

### 비교 2: 전위 + 중위로 트리 복원

| 조건 | 복원 가능 여부 | 설명 |
|:---|:---|:---|
| 전위 + 중위 | ✅ 가능 | 전위의 첫 번째 = 루트, 중위에서 루트 기준 좌우 분할 |
| 후위 + 중위 | ✅ 가능 | 후위의 마지막 = 루트, 중위에서 분할 |
| 전위 + 후위 | ❌ 불가 (일반) | 좌우 서브트리 경계를 구분할 수 없음 (풀 이진트리는 가능) |
| 중위만 | ❌ 불가 | 루트를 특정할 수 없음 |

### 과목 융합 관점
- **컴파일러**: 소스 코드를 추상 구문 트리(AST)로 파싱한 후, 후위 순회로 코드를 생성한다(피연산자 → 연산자 순으로 스택 기반 바이트코드 방출).
- **파일 시스템**: `du -sh /path` 명령은 디렉토리 크기를 **후위 순회**로 계산한다 — 하위 파일·디렉토리의 크기를 먼저 합산한 후 현재 디렉토리 크기를 결정한다.
- **데이터베이스**: B+Tree 인덱스의 범위 스캔(예: `WHERE id BETWEEN 10 AND 50`)은 중위 순회의 원리를 활용하여 리프 노드를 정렬 순서대로 연결 리스트처럼 따라간다.

- **📢 섹션 요약 비유**: 순회 방식 선택은 "읽기 순서" 선택과 같습니다. 소설은 처음부터(전위), 사전은 가나다순(중위), 시험 채점은 답부터(후위) 봅니다. 읽는 순서가 목적에 맞아야 정보를 올바르게 처리합니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — JSON/XML 직렬화 (전위)**: REST API 응답으로 트리 구조 데이터(조직도, 카테고리 계층)를 JSON으로 직렬화할 때 전위 순회를 사용한다. 부모 노드를 먼저 출력하고, 그 안에 자식 배열을 중첩하는 구조가 JSON의 자연스러운 형태이기 때문이다.

2. **시나리오 — 가비지 컬렉터의 마킹 단계 (전위/BFS)**: JVM의 Mark-and-Sweep GC는 루트 셋(Root Set)에서 출발하여 참조 그래프를 전위/BFS 순회하며 살아있는 객체를 마킹한다. 마킹되지 않은 객체는 가비지로 판정하여 수거한다.

### 도입 체크리스트
- **기술적**: 문제가 "부모 먼저"(전위), "정렬 순서"(중위), "자식 먼저"(후위) 중 어떤 패턴인지 판별했는가?
- **운영 및 보안적**: 재귀 깊이가 시스템 스택 한계를 초과할 가능성이 있는가? (트리 높이 > 1,000이면 반복 구현 필수)

### 안티패턴
- **후위 문제에 전위 적용**: 디렉토리 크기 계산에 전위 순회를 시도하면, 현재 디렉토리를 방문할 때 하위 디렉토리 크기가 아직 계산되지 않아 정확한 값을 얻을 수 없다.
- **BST 정렬에 전위/후위 사용**: 중위 순회만이 BST의 키를 오름차순으로 출력한다. 전위·후위는 정렬 순서를 보장하지 않는다.

- **📢 섹션 요약 비유**: 잘못된 순회를 고르면, 수학 시험에서 "문제를 읽기 전에 답을 쓰는"(전위로 후위 문제 풀기) 꼴입니다. 문제(자식)를 먼저 이해해야 답(부모)을 쓸 수 있습니다.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 순회 미활용 | 적절한 순회 활용 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | BST 정렬 출력에 별도 정렬 $O(N log N)$ | 중위 순회 $O(N)$ | **log N배** 빠름 |
| **정량** | 트리 직렬화에 임시 자료구조 사용 | 전위 순회로 직접 출력 $O(N)$ | 메모리 **50%** 절감 |
| **정성** | "트리에서 어떻게 접근할지 모르겠다" | 순회 패턴으로 문제 분류 | 트리 문제 해결 체계화 |

### 미래 전망
- **병렬 트리 순회**: GPU나 멀티코어에서 트리의 서브트리를 독립적으로 순회하여 병렬화. MapReduce의 트리 처리 패턴이 대표적이다.
- **영속 트리(Persistent Tree)와 순회**: 함수형 프로그래밍에서 이전 버전을 유지하는 트리의 순회는 시간 여행(Time Travel) 디버깅의 기반이다.

순회는 트리 문제 해결의 **시작점**이다. "이 문제는 부모를 먼저 처리하는가, 자식을 먼저 처리하는가?"라는 질문에 답하면 적합한 순회가 결정되고, 순회가 결정되면 해법의 골격이 완성된다.

- **📢 섹션 요약 비유**: 트리 순회는 요리 순서와 같습니다. 전위는 "밥부터 짓고 반찬 준비"(메인 먼저), 후위는 "반찬 다 만든 후 밥 배식"(서브 먼저), 중위는 "작은 반찬→밥→큰 반찬"(순서대로). 순서가 틀리면 식사가 안 됩니다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| 트리 구조 (BST, B-Tree) | 순회의 대상. BST 중위 순회 = 정렬 순서 출력. |
| 스택 (Stack) | 반복 순회의 핵심 자료구조. 재귀를 명시적 스택으로 대체. |
| 그래프 탐색 (BFS/DFS) | DFS = 전위/중위/후위, BFS = 레벨 순회. 트리 순회는 그래프 탐색의 특수 형태. |
| 컴파일러 (AST) | 구문 트리의 후위 순회 → 코드 생성. |

### 📈 관련 키워드 및 발전 흐름도

```text
[이진 트리 기본 구조]
    |
    v
[전위·중위·후위 순회 (현재 개념)]
    |
    +---> [BST 범위 쿼리 (중위 순회)]
    +---> [컴파일러 코드 생성 (후위 순회)]
    +---> [직렬화/역직렬화 (전위 + BFS)]
    +---> [Morris Traversal (O(1) 공간)]
```

### 👶 어린이를 위한 3줄 비유 설명

1. 가족 사진을 찍을 때 — 전위는 "아빠 먼저, 그다음 왼쪽 아이, 오른쪽 아이", 중위는 "왼쪽 아이, 아빠, 오른쪽 아이"(키 순서!), 후위는 "아이들 먼저, 아빠 마지막".
2. BST(이진 탐색 트리)에서 "왼쪽 아이 → 아빠 → 오른쪽 아이" 순서(중위)로 읽으면 숫자가 작은 것부터 큰 것 순으로 나와요!
3. 폴더 크기를 알려면? 하위 폴더부터 세야 하니까 후위 순회예요. "내 폴더 크기 = 왼쪽 폴더 크기 + 오른쪽 폴더 크기 + 내 파일 크기".
