## 미리 알고가기

- autoregressive: 이전 토큰을 바탕으로 다음 토큰을 순차 예측하는 방식임
- Transformer decoder: causal attention 기반 생성 구조임
- prompt: 모델이 응답을 생성할 때 참고하는 입력 문맥임

## Ⅰ. 개요

- **정의/개념**: GPT는 Transformer decoder 기반 자기회귀 언어 모델로, 앞선 토큰 문맥을 이용해 다음 토큰을 예측하며 텍스트 생성과 추론을 수행함
- **배경/필요성**: 자연스러운 문장 생성, 요약, 대화, 코드 작성처럼 연속적인 언어 생성 과제에는 생성 중심 구조가 필요함

## Ⅱ. 특징

- 대규모 사전학습으로 다양한 언어 패턴과 지식을 내재화함
- zero-shot, few-shot처럼 프롬프트 기반 적응이 가능함
- 생성 능력이 강해 다양한 태스크를 하나의 모델로 처리할 수 있음
- hallucination, 긴 컨텍스트 비용, 안전성 통제가 주요 과제임

## Ⅲ. 종류 및 비교

| 판단 기준 | BERT | GPT | RNN |
|:---|:---|:---|:---|
| 구조 | Encoder | Decoder | 순환 구조 |
| 강점 | 문맥 이해 | 생성, 추론 | 경량 시퀀스 |
| 병렬화 | 높음 | 높음 | 낮음 |
| 대표 적용 | 분류, QA | 대화, 요약, 코드 | 시계열, 전통 NLP |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 토큰 임베딩 | 입력 문맥을 벡터화하고 생성 시작점임 |
| causal self-attention | 미래 토큰을 보지 않고 현재까지 문맥만 참조하고 자기회귀 생성 핵심임 |
| decoder stack | 깊은 표현과 추론을 수행하고 성능을 좌우함 |
| next-token objective | 다음 토큰 예측 손실이며 사전학습 목표임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 프롬프트입력 | --> | 문맥인코딩 | --> | 다음토큰예측 | --> | 반복생성 |
+----------+     +----------+     +----------+     +----------+
```

1. **프롬프트입력**: 사용자 질의와 컨텍스트를 토큰화함
2. **문맥인코딩**: decoder가 현재까지 토큰 관계를 계산함
3. **다음토큰예측**: 가장 가능성 높은 다음 토큰 분포를 산출함
4. **반복생성**: 종료 조건까지 토큰 생성을 반복함

## Ⅵ. 문제점 및 해결 방안

1. **hallucination이 발생함**: 그럴듯하지만 틀린 내용을 생성할 수 있음
   - **해결 방안**: RAG, tool use, 출처 검증을 결합하고 factual accuracy로 검증함
2. **컨텍스트 길이와 비용이 커짐**: 긴 입력은 지연과 비용을 높임
   - **해결 방안**: 요약, chunking, retrieval 기반 컨텍스트 최적화를 적용하고 latency, token cost로 검증함
3. **안전성과 권한 통제가 필요함**: 부적절 응답, 데이터 유출 위험이 있음
   - **해결 방안**: guardrail, 정책 필터, 로그 모니터링을 적용하고 policy violation rate로 검증함

## Ⅶ. 적용 사례

- 고객지원 챗봇: 질의응답과 요약을 수행함, 확인 지표는 해결률과 CSAT임
- 코드 보조: 함수 생성과 설명을 지원함, 확인 지표는 acceptance rate임
- 문서 업무 자동화: 초안 작성과 분류를 수행함, 확인 지표는 처리시간 절감률임

## Ⅷ. 결론

GPT의 핵심은 생성 범용성에 있으므로, 모델 성능만 볼 것이 아니라 사실성 보강과 운영 통제를 함께 설계해야 실무 적용이 가능함.
