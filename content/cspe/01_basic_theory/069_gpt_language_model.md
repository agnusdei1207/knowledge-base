# 📖 【암기용】 개념 완전 이해

> 목적: GPT 언어 모델을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 다음 토큰 예측으로 문장을 생성하는 Transformer Decoder 기반 언어모델
- **왜 필요한가**: 검색·분류 중심 NLP를 넘어 요약, 번역, 코드 작성, 대화처럼 새 텍스트를 생성하는 업무가 필요해졌다.
- **핵심 직관**: 지금까지 나온 단어들을 보고 다음에 올 확률이 가장 높은 토큰을 반복 선택해 문장을 만든다.

## 깊이 이해
- **배경·문제의식**: RNN 기반 언어모델은 긴 문맥 처리와 병렬 학습에 제약이 있었다. GPT는 Self-Attention과 causal mask로 이전 토큰만 참조하면서 대규모 말뭉치의 패턴을 학습한다.
- **작동 원리**: 입력 토큰을 embedding으로 바꾼 뒤 Decoder block을 통과시키고, softmax로 다음 토큰 확률분포를 계산한다. temperature, top-k, top-p가 생성 다양성을 조절한다.
- **비유**: 문장을 한 글자씩 이어 쓰는 자동완성이다. 다만 앞 문장 전체를 attention으로 참조하고, 확률 분포에서 선택 기준을 바꿔 보수적 답변과 창의적 답변을 조절한다.
- **구체 예시**: 고객센터 FAQ 요약에서 temperature 0.2는 동일한 정책 문구를 재현하는 데 적합하고, temperature 0.8은 마케팅 문안 생성처럼 다양한 후보가 필요한 업무에 사용한다.
- **흔한 오해·주의점**: GPT는 지식을 항상 사실로 보장하지 않는다. RAG, tool calling, citation, guardrail을 붙여 근거성·최신성·보안 통제를 설계해야 한다.

## 연결 개념
- Transformer Decoder — GPT의 기본 구조
- BERT — Encoder 기반 이해 모델 비교 대상
- RAG — 외부 지식 검색을 결합해 환각과 최신성 문제 보완

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPT는 causal self-attention으로 이전 토큰을 참조해 다음 토큰 확률을 예측하는 Decoder-only 생성형 언어모델이다.
> 2. **가치**: 요약·번역·코드·대화 생성 업무를 프롬프트와 API로 구현하며, RAG·도구 호출 결합 시 기업 지식 업무 자동화가 가능하다.
> 3. **판단 포인트**: 정확성·비용·지연시간·정보보호 요구에 따라 prompt, fine-tuning, RAG, 온프레미스 모델을 선택한다.

---

## Ⅰ. 개요 및 필요성

GPT는 다음 토큰 예측 기반 생성형 언어모델이다. 기업 업무는 문서 요약·질의응답·코드 생성처럼 정형 규칙만으로 처리하기 어려운 텍스트 생성 수요가 증가했다. GPT 도입은 모델 성능보다 근거성, 개인정보, 비용, 지연시간 통제 설계가 핵심이다.

---

## Ⅱ. 구조 및 구성요소

```text
프롬프트 -> 토큰화 -> Decoder Block Stack -> 다음 토큰 분포 -> 생성 결과
             +-> system/developer/user 지시
             +-> RAG/tool/guardrail
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tokenizer | 입력 문장을 토큰 ID로 변환 | 컨텍스트 길이와 비용 결정 |
| Decoder Block | causal attention과 FFN 수행 | 이전 토큰만 참조 |
| Sampling | 다음 토큰 선택 | temperature, top-p, max token |
| 통제 계층 | 근거 검색·도구 호출·필터링 | RAG, function calling, DLP |

> 요약: GPT는 프롬프트를 토큰화해 Decoder Stack으로 다음 토큰 확률을 계산하고, 통제 계층으로 업무 적합성을 확보한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 입력 -> 프롬프트 구성 -> 토큰 확률 계산 -> 샘플링
-> 후처리/검증 -> 응답 반환 -> 로그·평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 역할·문맥·제약을 프롬프트로 구성 | prompt version 추적 |
| 2 | causal attention으로 다음 토큰 예측 | perplexity, logprob |
| 3 | sampling과 stop 조건 적용 | temperature 0.0~1.0 |
| 4 | 근거·보안·품질 검증 | hallucination rate, PII 검출 |

> 요약: GPT는 프롬프트 조건에 따라 토큰을 반복 생성하고, 후처리에서 사실성·보안·품질을 검증한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 자연어 지시로 요약·생성·변환 수행 | task success rate 90% 목표 |
| 한계 | 환각·최신성·민감정보 노출 위험 | RAG citation, DLP, 감사로그 필요 |
| 비교 대상 | BERT는 이해, GPT는 생성 | 업무가 분류인지 생성인지 구분 |

> 요약: GPT는 생성 업무에 적합하지만, 사실성·보안·비용을 별도 아키텍처로 통제해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 규칙 엔진·템플릿 | 프롬프트 기반 생성 | 예외 문장 유형 월 100건 이상 |
| 비용/성능 | 개발비 높고 추론비 낮음 | API/서빙 비용 발생, 개발 기간 단축 | 요청당 비용, p95 지연 |
| 운영/위험 | 결과 예측 가능 | 환각·prompt injection | 근거 문서와 guardrail 필요 |

> 요약: 변화가 많은 텍스트 생성 업무는 GPT를 선택하되, 정답성이 핵심인 업무는 RAG·검증 계층을 필수로 둔다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 환각 | 내부 지식 미제공·확률 생성 | RAG, citation, answer abstain | hallucination rate 3% 이하 |
| 정보유출 | 프롬프트에 PII 포함 | DLP 마스킹, RBAC, 로그 암호화 | PII 탐지 100% 차단 |
| 비용 초과 | 긴 컨텍스트·재시도 | token budget, cache, model routing | 월 예산 대비 90% 알림 |

> 요약: GPT 위험은 환각·정보유출·비용이며, 검색근거·데이터 통제·토큰 예산으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 품질/정확도 | task success 90% 이상, hallucination 3% 이하 | golden set, human eval |
| 성능/비용 | p95 3초 이하, 요청당 비용 상한 | APM, token usage log |
| 운영/보안 | RBAC, 감사로그, PII 마스킹 | SIEM, DLP 리포트 |

> 요약: GPT 서비스는 품질·비용·보안 지표를 릴리스 승인 기준으로 삼아야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. FAQ·문서요약은 temperature 0.2, max token, system prompt version을 고정하고 golden set 100건으로 회귀 평가함
2. 내부지식 QA는 Vector DB RAG와 citation을 붙이고, 답변 근거 미검색 시 "답변 불가" 정책을 적용함
3. 운영은 token budget, DLP 마스킹, RBAC, 감사로그를 API Gateway에서 강제하고 월별 hallucination rate를 측정함

**결론 (2줄):**
- 기술사 판단: 창작·요약은 GPT 단독, 사실 기반 QA는 RAG 결합, 규제 데이터는 사내 모델 또는 전용 인스턴스를 선택함
- 향후 방향: GPT는 멀티모달 입력, 도구 호출, 에이전트 워크플로우와 결합해 업무 자동화 플랫폼으로 확장됨
