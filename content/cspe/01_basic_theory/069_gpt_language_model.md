## 미리 알고가기

- 자기회귀: 이전 토큰들을 조건으로 다음 토큰을 하나씩 예측하는 생성 방식임
- Transformer 디코더: 미래 토큰을 보지 못하도록 masked self-attention을 사용하는 구조임
- 인과 마스크: 현재 위치 이후의 토큰 정보를 차단하는 삼각 형태의 attention 제한임
- LM Head: 디코더 출력 벡터를 어휘별 다음 토큰 확률로 변환하는 출력층임
- 샘플링: top-k, top-p, temperature 등으로 다음 토큰 선택의 다양성을 조정하는 방법임

## Ⅰ. 개요

- **정의**: GPT는 Transformer 디코더가 이전 토큰 시퀀스를 기준으로 다음 토큰 확률을 예측하고 이를 반복해 텍스트를 생성하는 자기회귀 언어 모델임. 대화, 요약, 번역, 코드 작성처럼 자연어 또는 코드 출력을 순차 생성하기 위해 사용함
- **배경/필요성**: BERT 계열은 문맥 이해에는 강하지만 양방향 입력을 전제로 하므로 앞의 문맥만 보고 다음 내용을 이어 쓰는 생성 태스크에는 적합하지 않음
- **비유**: 이미 쓴 문장만 읽고 다음 단어를 계속 골라 문서를 완성하는 작가와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPT 생성 원리 설명 | 자기회귀, 인과 마스크, 다음 토큰 예측 | BERT 양방향 인코더와 혼동 |
| 운영 위험 설명 | 환각, 정렬, 비용, 보안 통제 | 생성 품질만 장점으로 나열 |

> 요약: GPT는 이전 토큰만 참조하는 디코더 구조로 다음 토큰을 반복 예측해 문장을 생성하는 NLG 중심 모델임

## Ⅱ. 특징/비교

| 판단 기준 | BERT | GPT |
|:---|:---|:---|
| attention 방향 | 좌우 문맥을 모두 참고함 | 현재 이전 토큰만 참고함 |
| 주요 학습 목표 | 마스킹된 토큰과 문장 관계를 맞힘 | 다음 토큰 확률을 최대화함 |
| 적합 태스크 | 분류, 검색, NER, QA | 대화, 생성, 요약, 코드 작성 |
| 운영 고려 | 출력이 비교적 제한적임 | 자유 생성으로 환각과 가드레일이 중요함 |

> 요약: GPT는 이해보다 생성이 핵심인 태스크에서 강하지만 생성 자유도만큼 검증과 통제가 필요함

- **프롬프트 민감성**: 같은 지식이라도 지시 방식, 예시, 출력 형식에 따라 결과 품질이 달라짐
- **확률적 생성**: temperature와 sampling 설정이 창의성, 일관성, 재현성을 조절함
- **컨텍스트 한계**: 긴 입력을 넣어도 모델이 모든 내용을 동일한 품질로 활용하지는 않으므로 검색·요약 전략이 필요함

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Prompt      | ---> | Token + Pos | ---> | Decoder     |
| Text        |      | Embedding   |      | Blocks x N  |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Causal Mask | ---> | LM Head     | ---> | Next Token  |
| no future   |      | Softmax     |      | Distribution|
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 프롬프트 | 모델이 생성 조건으로 삼는 사용자 지시와 문맥 정보임 | 작성 지시서 |
| 토큰·위치 임베딩 | 입력 토큰과 순서 정보를 벡터로 변환함 | 문장 좌표 |
| masked self-attention | 미래 토큰을 차단하고 이전 문맥의 중요도를 계산함 | 앞만 보는 시야 |
| LM Head | 디코더 출력을 어휘별 확률 분포로 변환함 | 다음 단어 투표함 |
| 디코딩 전략 | greedy, beam, top-k, top-p 등 다음 토큰 선택 규칙임 | 말투 조절기 |

> 요약: GPT는 프롬프트를 토큰화하고 디코더가 인과 마스크로 문맥을 읽어 다음 토큰 확률을 반복 출력하는 구조임

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Tokenize  | --> | Decode    | --> | Sample    | --> | Append    |
| Prompt    |     | Context   |     | Next Tok  |     | Until End |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
input ids          causal attention    probability       full answer
```

1. **프롬프트 입력**: 사용자 지시, 예시, 참고 문서를 토큰화하고 컨텍스트 창 안에 배치함
2. **문맥 계산**: 디코더 블록이 인과 마스크를 적용해 이전 토큰의 attention 가중치를 계산함
3. **다음 토큰 선택**: LM Head가 만든 확률 분포에서 디코딩 전략에 따라 다음 토큰을 선택함
4. **반복·종료**: 선택 토큰을 입력 뒤에 붙이고 종료 토큰, 길이 제한, 정책 조건에 도달할 때까지 반복함

> 요약: GPT 추론은 프롬프트를 조건으로 다음 토큰을 고르고 다시 조건에 추가하는 반복 생성 루프임

## Ⅴ. 문제점

- **P1 환각**: 모델이 내부 확률 패턴만으로 사실처럼 보이는 부정확한 내용을 생성할 수 있음
- **P2 정렬·안전 위험**: 사전학습 데이터의 편향이나 악의적 프롬프트로 유해하거나 정책 위반 출력이 나올 수 있음
- **P3 추론 비용과 지연**: 토큰을 순차 생성하므로 긴 답변과 대형 모델에서 GPU 비용과 응답 시간이 커짐

> 요약: GPT 운영은 사실성, 안전성, 비용을 동시에 통제하지 않으면 서비스 품질과 위험이 빠르게 악화됨

## Ⅵ. 개선방안

- **P1 대응**: RAG, 출처 기반 응답, 후처리 검증, 불확실성 표시를 결합함 (확인: factuality, 근거 일치율)
- **P2 대응**: RLHF, 정책 가드레일, 입력·출력 필터, 감사 로그를 적용함 (확인: 유해 출력률, 우회 프롬프트 차단률)
- **P3 대응**: 캐싱, batch serving, quantization, MoE 또는 소형 모델 라우팅으로 비용을 줄임 (확인: token/s, p95 지연)

> 요약: GPT는 검색 보강, 안전 정렬, 추론 최적화를 함께 설계해야 생성 능력을 실서비스 품질로 연결할 수 있음

## Ⅶ. 전망

- **향후 발전 방향**: GPT 계열은 멀티모달 입력, 도구 호출, 에이전트 워크플로와 결합해 단순 생성에서 작업 수행 모델로 확장될 전망임
- **기술사적 판단**: 생성이 필요한 업무에는 GPT가 강하지만, 폐쇄형 분류·검색 업무에는 비용과 통제성을 고려해 BERT 또는 전통 모델도 비교해야 함
- **기술사 제언**: 답안에서는 디코더 자기회귀 구조와 함께 환각·정렬·비용 대응을 포함해야 기술 선택 판단이 완성됨
- **답안 포인트**: GPT 도입 판단은 생성 품질뿐 아니라 근거 검증, 가드레일, 토큰 비용까지 포함함
