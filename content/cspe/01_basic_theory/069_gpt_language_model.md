# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: GPT는 **자기회귀 언어 모델**(Autoregressive Language Model)의 한 갈래로, 트랜스포머(Transformer)의 **디코더**(Decoder)만 층층이 쌓아 지금까지 나온 단어들을 보고 "다음 단어"를 순차적으로 생성하는 모델이다.
- **왜 필요한가**: 자연스러운 텍스트 생성(기사 작성, 대화, 코드 생성)은 이미 쓴 부분까지만 보고 다음 글자를 이어가는 사람의 글쓰기와 같은 구조다. 문맥을 양방향으로 다 열어 두면(BERT 방식) 오히려 "다음에 뭐가 와야 하는지"를 순서대로 만들어낼 수 없다.
- **핵심 직관**: "나는 오늘 밥을..." 이 주어지면 다음에 "먹었다"가 올 확률이 가장 높다고 계산해 토큰 하나를 뽑고, 그 결과를 다시 입력에 이어붙여 또 다음 토큰을 뽑는 과정을 반복한다(Autoregressive) — 이 반복 자체가 문장을 "생성"하는 절차다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 자기회귀 언어 모델(Autoregressive LM) | 지금까지 생성된 토큰을 입력으로 다시 넣어 다음 토큰을 순차 예측하는 모델 — GPT가 속하는 **상위 범주** | 앞서 부른 소절을 듣고 바로 다음 소절을 이어 부르는 것을 반복 |
| 트랜스포머 디코더(Decoder) | 트랜스포머 중 문장을 순차적으로 "생성"하는 절반 — GPT는 이것만 사용(인코더는 068 BERT가 사용) | 앞 내용만 보고 다음 문장을 이어 쓰는 소설가 |
| Masked Self-Attention(인과적 마스킹) | Self-Attention 계산 시 자기 자신보다 뒤(미래)에 있는 토큰 정보를 강제로 차단하는 기법 | 시험 볼 때 앞 문제 답만 보이고 뒤 문제 답은 가려진 답안지 |
| Next Token Prediction | 현재까지의 문맥으로 어휘 사전 전체에 대한 확률분포를 구해 다음 토큰 하나를 뽑는 사전학습 과제 | 앞 글자들을 보고 다음 글자를 맞히는 끝말잇기 |
| BPE(Byte Pair Encoding) | 자주 붙어 등장하는 문자 쌍을 반복 병합해 서브워드 사전을 만드는 토큰화 방식 | 자주 붙어 나오는 글자 조합을 하나의 스티커로 묶어 재사용 |
| SFT(Supervised Fine-Tuning) | 사람이 작성한 지시-응답 쌍 데이터로 "지시를 따르는" 형식을 학습시키는 미세조정 단계 | 모범답안 예시를 보며 답변 형식을 따라 하는 연습 |
| 보상 모델(Reward Model) | 같은 질문에 대한 여러 답변에 사람이 매긴 선호 순위를 학습해, 답변에 점수를 매기는 모델 | 여러 답안의 순위를 매기는 채점관을 흉내 낸 AI |
| RLHF(인간 피드백 강화학습) | 보상 모델 점수를 최대화하는 방향으로 PPO 알고리즘을 이용해 GPT 자체를 강화학습으로 재조정하는 단계 | 채점관 점수를 최대한 잘 받는 방향으로 답변 습관을 계속 교정 |
| In-context Learning | 파라미터를 전혀 바꾸지 않고, 프롬프트 안 몇 개의 예시만으로 새로운 패턴을 그 자리에서 수행하는 능력 | 문제지 맨 위에 예시 2~3개를 보여주면 그 규칙을 바로 따라 푸는 것 |
| Temperature(샘플링 온도) | 다음 토큰 확률분포를 얼마나 평평하게(다양) 또는 뾰족하게(확정적으로) 만들지 조절하는 값 | 온도를 높이면 도전적인 답, 낮추면 안전한 정답 위주로 선택 |

## 깊이 이해

### 왜 디코더만 떼어냈나 (배경 — 068 BERT와 공유하는 부분은 요약만)
- 068에서 다뤘듯 트랜스포머는 원래 인코더+디코더 쌍으로 시작됐다. GPT는 반대로 "이해"가 아니라 "생성"에 집중해 디코더만 떼어내 계속 층을 늘리는 방향(Scale-up)으로 발전했다. Self-Attention의 Query·Key·Value 계산 자체는 068과 같은 수식(softmax(QKᵀ/√d_k)·V)을 쓴다 — 차이는 바로 다음 항목의 마스킹 하나뿐이다.

### Masked(인과적) Self-Attention을 수치로 이해하기
- BERT의 Self-Attention은 모든 토큰이 서로를 다 볼 수 있는 완전 행렬이지만, GPT는 "미래 위치"에 해당하는 어텐션 점수를 전부 -∞로 만들어(소프트맥스 통과 후 0이 되도록) 자기 자신과 그 이전 토큰만 보게 강제한다.
- 예: 5개 토큰짜리 문장에서 3번째 토큰은 1·2·3번 토큰만 참조할 수 있고 4·5번은 마스킹된다. 어텐션 가중치 행렬을 그리면 대각선 왼쪽 아래만 값이 있고 오른쪽 위는 전부 0인 하삼각행렬(Lower-triangular) 모양이 된다.
- 이 마스킹 하나가 BERT(양방향 이해)와 GPT(단방향 생성)를 가르는 유일한 구조적 차이다.

### Autoregressive 생성을 수치로 이해하기
- 프롬프트 "대한민국의 수도는"이 주어지면, 모델은 어휘 사전(수만~수십만 개 토큰) 전체에 대한 확률분포를 계산한다. 예: {"서울": 0.82, "부산": 0.04, "평양": 0.02, 그 외: 0.12}. 이 중 "서울"을 다음 토큰으로 뽑는다.
- 뽑힌 "서울"을 다시 입력에 이어붙여 "대한민국의 수도는 서울"을 새 입력으로 넣고, 다음 토큰("이다")을 또 예측한다. 이 과정을 종료 토큰이 나올 때까지 반복하는 것이 Autoregressive 생성이다.

### 사전학습 → SFT → RLHF를 수치로 이해하기
1. 사전학습: 인터넷 텍스트 수천억 토큰으로 "다음 토큰 맞히기"만 반복 — 이 단계는 지시를 "따르는" 능력이 아니라 언어 패턴 자체만 익힌다.
2. SFT: 사람이 작성한 지시-모범답변 쌍(수만 건 규모)으로 "질문엔 답으로 응답한다"는 형식을 학습시킨다.
3. 보상 모델 학습: 같은 질문에 대해 모델이 낸 여러 답변(예: 4개)을 사람이 순위 매김(1등~4등) → 이 순위 데이터로 별도 모델이 "좋은 답변에 높은 점수"를 주는 점수 함수를 학습.
4. RLHF: 원래 GPT가 보상 모델 점수를 최대화하도록 PPO(정책 경사) 알고리즘으로 재조정한다. 이 단계에서 유해·거짓 답변에는 낮은 보상을 줘 억제한다.

### 모델 규모와 확장 법칙(Scaling Law)을 수치로 이해하기
- GPT-1(2018) 파라미터 약 1억 1,700만 개, GPT-2(2019) 약 15억 개, GPT-3(2020) 약 1,750억 개로 세대마다 파라미터가 약 10배 이상씩 늘었다.
- 확장 법칙: 파라미터 수·데이터량·연산량을 함께 늘리면 손실(loss)이 멱법칙(power law)으로 꾸준히 줄어든다는 경험적 관찰이다. "일단 크게 만들면 성능이 예측 가능하게 좋아진다"는 것이 GPT 계열 확장의 근거가 됐다.
- 컨텍스트 창(한 번에 참조 가능한 토큰 수)도 함께 늘어, GPT-3는 2,048토큰, 이후 세대는 수만 토큰까지 확장됐다 — 참조 범위가 넓을수록 긴 대화·문서를 기억한다.

### 비유와 흔한 오해
- 비유: 눈을 가리고 앞사람이 부른 소절만 듣고 다음 소절을 이어 부르는 게임을 수조 번 연습한 모창 가수와 같다. 다음에 무슨 소절이 올지는 몰라도, "이런 상황엔 이런 소절이 자연스럽다"는 확률 감각만 극도로 정교해진 것이다.
- 오해: GPT가 사실을 "알고" 답하는 게 아니라, 훈련 데이터 패턴상 가장 그럴듯한 다음 토큰을 확률적으로 이어 붙일 뿐이다. 그래서 그럴듯하지만 틀린 문장(할루시네이션)이 필연적으로 나온다 — 이는 구조적 한계이지 버그가 아니다.

## 연결 개념
- 트랜스포머 인코더(068 BERT) — 같은 Self-Attention 수식을 쓰되, 마스킹 유무로 이해(양방향)와 생성(단방향)이 갈린다.
- RLHF — 보상 모델과 PPO로 모델 출력을 인간 선호에 정렬하는 절차.
- 프롬프트 엔지니어링/In-context Learning — 가중치 수정 없이 지시문만으로 작업을 바꾸는 기법.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 디코더 전용(Decoder-only) 구조와 자기회귀(Autoregressive) 생성 방식, 그리고 In-context Learning(Zero/Few-shot)의 가능성을 명확히 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPT(Generative Pre-trained Transformer)는 트랜스포머 디코더만을 층층이 쌓아올린 자기회귀(Autoregressive) 기반 대규모 언어 모델이다.
> 2. **가치**: 대규모 텍스트로 다음 토큰 예측(Next Token Prediction)을 사전학습하여, 가중치 수정 없이 프롬프트만으로 다중 태스크를 수행(In-context Learning)한다.
> 3. **판단 포인트**: 파인튜닝 의존도를 낮춘 범용 생성 해결사 역할을 하지만, 환각(Hallucination) 통제를 위해 RAG 및 가드레일 도입이 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생성형 모델의 아키텍처적 특성 이해 | Decoder-only, Autoregressive, Masked Self-Attention | 인코더 구조(BERT)와 혼용 서술 금지 |
| LLM 패러다임 변화 인식 확인 | In-context Learning, Zero-shot/Few-shot 성능 | 무조건적인 Fine-tuning 필요성 역설 금지 |
| 상용화 한계 및 리스크 통제 방안 | 할루시네이션, 프롬프트 인젝션, 최신 데이터 결여 | RAG, 프롬프트 가드레일 등 극복 방안 누락 |

> 요약: 디코더 자기회귀 방식의 기술적 근간을 바탕으로, 범용 인공지능 도구로서의 장점과 환각(Hallucination) 리스크 통제 방안을 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 트랜스포머 디코더 블록을 다층으로 쌓아 다음 단어 예측을 수행하는 언어 생성 특화 사전학습 모델
- 배경: 기존 모델들은 태스크(번역/요약 등)마다 별도의 아키텍처 설계와 라벨링 데이터에 기반한 파인튜닝을 요구
- 필요성: 거대 코퍼스로 사전학습 1회 수행 후, 지시어(Prompt)만으로 다양한 작업을 즉시 수행(Zero-shot)하는 범용 파운데이션 모델 필요

## Ⅱ. 구조 및 구성요소

```text
Input Tokens -> Masked Self-Attention -> Feed Forward Network -> Softmax -> Next Token
                     | (과거 문맥만 참조, 미래 참조 차단)
                +---- Decoder Block (N번 반복) ----+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Transformer Decoder | 인코더 없이 디코더만 적층 (Decoder-only) | 대규모 층(Layer) 확장에 유리 (Scale-up) |
| Masked Self-Attention | 현재 시점(t) 예측 시 미래 시점(t+1~) 정보 참조를 마스킹 | 하삼각행렬(Lower-triangular) 형태 마스크 적용 |
| Autoregressive (자기회귀) | 생성된 토큰 $y_t$를 다음 단계 $t+1$의 입력으로 재사용 | 단방향(Left-to-Right) 텍스트 생성 |
| BPE Tokenization | 단어를 서브워드 단위로 쪼개어 어휘 사전(Vocabulary) 구축 | OOV(Out-of-Vocabulary) 빈도 축소 |

> 요약: 미래 정보 참조를 차단하는 마스크드 셀프 어텐션과 자기회귀(Autoregressive) 구조를 통해 문장을 순차적으로 생성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Pre-training (Next Token 예측) -> SFT (지도학습 미세조정) -> Reward Model 학습 -> RLHF (정렬)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사전학습 (Pre-training) | 대규모 코퍼스로 다음 단어 확률 학습 | Loss 값 하락 곡선 점검 |
| 2 | SFT (Supervised Fine-Tuning) | 프롬프트-답변 쌍 데이터로 지시어 수행 훈련 | 지시 추종성(Instruction Following) 확인 |
| 3 | 보상 모델 (Reward Model) | 다수 출력물에 대해 인간 선호도 기반 점수 부여 | 인간 피드백 정확도 스코어 |
| 4 | RLHF (강화학습 정렬) | PPO 알고리즘 기반으로 보상을 극대화하여 인간 가치관 정렬 | 혐오·유해 발언 생성률 0.1% 이하 억제 |

> 요약: 대규모 무지도 사전학습 이후, SFT와 RLHF를 통해 인간의 의도(Alignment)에 부합하는 유용한 AI 어시스턴트로 완성된다.

## Ⅳ. 특징 (In-context Learning 중심)

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| Zero-shot / Few-shot | 파라미터 업데이트 없이 프롬프트 예시만으로 새로운 패턴 인식 및 작업 수행 | 모델 스케일이 커질수록 발현(Emergent) 현상 뚜렷 |
| 확장 법칙 (Scaling Law) | 파라미터 수, 데이터, 연산량이 증가할수록 멱법칙으로 손실 감소 및 성능 향상 | 대규모 컴퓨팅 인프라 투자의 정당성 확보 |
| 단일 범용 아키텍처 | 텍스트 생성, 번역, 요약 등 모든 태스크를 Text-to-Text 인터페이스로 통일 | 별도 태스크별 네트워크 재설계 불필요 |

> 요약: 가중치 갱신(Fine-Tuning) 없이 프롬프트 문맥 파악만으로 다양한 작업을 수행(In-context Learning)하는 것이 최대 강점이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Greedy/Beam Search 디코딩 | Sampling 기반 디코딩 (Top-k/Top-p) | 선택 기준 |
|:---|:---|:---|:---|
| 생성 방식 | 매 스텝 최고 확률 토큰(Beam은 상위 N개 후보) 선택 | 확률 분포에서 무작위 추출, temperature로 다양성 조절 | 정답 고정형 출력 vs 창작형 출력 |
| 출력 특성 | 결정적(Deterministic), 반복·단조 표현 위험 | 비결정적, 다양성 확보되나 일관성 저하 가능 | 번역/요약(정확성) vs 대화/창작(다양성) |
| 연산 부하 | Beam width에 비례해 연산량 증가 | 단일 forward pass, 연산량 상대적으로 적음 | 응답 지연시간 vs 출력 품질 요구 수준 |

> 요약: 사실 정확성이 중요한 태스크는 Greedy/Beam 계열을, 다양성이 필요한 대화·창작 태스크는 Top-k/Top-p 샘플링을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 환각 (Hallucination) | 자기회귀의 확률적 생성 방식에 따른 사실 결여 | RAG(검색 증강 생성) 도입으로 외부 정보 근거 주입 | 답변 내 정보 출처 기반 재현율 검증 |
| 프롬프트 인젝션 | 악의적 프롬프트가 기존 시스템 지시어를 무력화 | 입력단 Guardrail 필터링 및 지시어 샌드박싱 적용 | 모의해킹 프롬프트 차단율 99% 달성 |

> 요약: 생성 과정의 환각(Hallucination) 방지를 위해 RAG 아키텍처를 결합하고, 악의적 입력 통제를 위한 프롬프트 가드레일을 구성해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 응답 정확도 | 근거 문서 기반 답변 일치율(Faithfulness) 90% 이상 | RAG 근거-답변 정합성 자동 평가 |
| 생성 다양성 | 동일 프롬프트 반복 출력 시 중복률 억제 | Self-BLEU, distinct-n 지표 측정 |
| 안전성 | 유해·편향 응답 발생률 최소화 | 레드팀 테스트, 콘텐츠 필터 로그 분석 |

> 요약: GPT 도입 효과는 근거 일치율, 생성 다양성, 유해 응답 억제율을 함께 측정해야 판단할 수 있다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 기반 지식 챗봇: 사내 규정을 벡터화하고 검색된 관련 문서를 프롬프트 컨텍스트에 삽입하여 GPT가 환각 없이 정확히 답변하도록 구현
2. 코드 생성 자동화: 형상관리 시스템과 연동하여 커밋 발생 시 변경 코드를 요약하고, 사내 코딩 컨벤션 위반 항목을 지적하는 자동 리뷰 코멘트 생성
3. 동적 데이터 리포팅: Function Calling을 통해 외부 실시간 API 매출 쿼리를 수행한 뒤, 반환된 데이터를 자연어 임원 보고서로 자동 생성

**결론 (2줄):**
- 기술사 판단: GPT 도입의 성공 여부는 모델 자체의 성능보다, RAG를 통한 "환각 통제"와 Prompt Engineering을 통한 "지시 정렬" 역량에 달려있다.
- 향후 방향: 단순 텍스트 모델을 넘어 시각, 청각 정보를 동시에 처리하는 LMM(Large Multimodal Model)으로 파운데이션 아키텍처가 진화하고 있다.
