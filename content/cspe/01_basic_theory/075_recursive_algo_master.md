# 075. 재귀 알고리즘과 마스터 정리 (Recursive Algorithm Master Theorem)

## Ⅰ. 개요

- **정의/개념**: 재귀 알고리즘($Recursive$ $Algorithm$)은 하나의 문제를 동일한 형태의 더 작은 하위 문제로 분할하여 해결하는 방식이며, 마스터 정리는 이러한 분할 정복($Divide$-$and$-$Conquer$) 구조의 시간 복잡도를 공식화하여 판정하는 수학적 분석 도구임
- **배경/필요성**: 병합 정렬, 이진 탐색 등 전형적인 재귀 구조의 성능 분석 시, 매번 재귀 트리를 그리거나 반복 대입법을 수행하는 비효율을 제거하고 $a, b, f(n)$ 세 가지 변수만으로 점근적 복잡도($Big$-$O$)를 즉시 도출하기 위해 필수적임

## Ⅱ. 특징 및 비교

### 1. 재귀 알고리즘 분석 기법 비교

| 판단 기준 | 반복 대입법 ($Iteration$) | 재귀 트리 ($Recursion$ $Tree$) | 마스터 정리 ($Master$ $Theorem$) |
|:---|:---|:---|:---|
| **분석 방식** | 재귀식을 일반항으로 전개 | 노드별 비용 합산 시각화 | $T(n) = aT(n/b) + f(n)$ 공식 대입 |
| **적용 범위** | 모든 재귀식 가능 | 직관적 구조 파악 시 유리 | 특정 정형 구조 ($a, b$ 상수) 제한 |
| **연산 속도** | 느림 (수식 계산 복잡) | 보통 (층별 합계 계산 필요) | 매우 빠름 (조건 비교 즉시 판정) |
| **정밀도** | 매우 높음 (상수항 포함 가능) | 높음 | 높음 (차수 중심) |

> 요약: 마스터 정리는 실무적으로 가장 빈번히 발생하는 분할 정복 알고리즘의 성능을 10초 이내에 판정할 수 있는 '분석 단축키'임

### 2. $PPA$ 관점의 트레이드오프 ($Trade$-$offs$)
- **Performance**: 재귀 호출은 함수 오버헤드로 인해 반복문($Iteration$)보다 절대적 실행 시간이 길어질 수 있음 ($O(n \log n)$ 차수는 동일해도 상수 계수 차이 발생)
- **Area(Memory)**: 호출 스택($Call$ $Stack$) 점유로 인해 재귀 깊이가 깊어질수록 메모리 부족($Stack$ $Overflow$) 위험이 존재함
- **Trade-off**: 코드의 가독성과 구현 편의성($Recursive$) vs 시스템 자원 안정성($Iterative$) 사이의 전략적 선택이 필요함

## Ⅲ. 구성요소/구조

### 1. 마스터 정리 공식 인사이트 ($Architecture$ $Insight$)
공식: $T(n) = aT(n/b) + f(n)$
- **$a$ ($a \ge 1$)**: 분할되는 하위 문제의 개수
- **$b$ ($b > 1$)**: 하위 문제로 나뉠 때 감소하는 크기 비율
- **$f(n)$**: 문제를 나누고 합치는 과정($Divide/Combine$)에서 발생하는 오버헤드 비용

### 2. 성능 판정 3대 케이스 (기준값: $n^{\log_b a}$)
1. **Case 1 ($Leaf$ 비대형)**: $f(n) = O(n^{\log_b a - \epsilon})$ 이면, $T(n) = \Theta(n^{\log_b a})$
2. **Case 2 (균형형)**: $f(n) = \Theta(n^{\log_b a})$ 이면, $T(n) = \Theta(n^{\log_b a} \log n)$
3. **Case 3 ($Root$ 비대형)**: $f(n) = \Omega(n^{\log_b a + \epsilon})$ 이면, $T(n) = \Theta(f(n))$
   - 단, $af(n/b) \le cf(n)$ (정규성 조건) 만족 필수

### 3. 재귀 트리 구조 도식
```text
            [Root: f(n)]              --- Level 0 Cost
           /     |     \
    [f(n/b)]  [f(n/b)]  [f(n/b)]      --- Level 1 Cost (a * f(n/b))
    /  |  \   /  |  \   /  |  \
   ..........(a^i개)..........        --- Level i Cost (a^i * f(n/b^i))
```

## Ⅳ. 문제점 및 개선방안

### 1. 실무적 문제점 및 대응 전략
1. **[마스터 정리 적용 불가 케이스 발생]**: $a$가 상수가 아니거나(예: $T(n) = nT(n/2)$), $f(n)$이 다항식이 아닌 경우(예: $2^n$) 분석 불가
   - **개선방안**: 더 일반화된 공식인 $Akra$-$Bazzi$ 정리를 적용하거나 직접 재귀 트리를 그려서 층별 합의 급수를 계산함 (확인: 수렴 여부)
2. **[호출 스택 과부하]**: 재귀 깊이가 로그 스케일($\log n$)을 넘어 선형($n$)으로 증가할 때 시스템 가용성 저하
   - **개선방안**: 꼬리 재귀 최적화($Tail$ $Recursion$ $Optimization$)를 적용하거나, 명시적인 $Stack$ 자료구조를 사용한 $Iterative$ 방식으로 전환 (확인: 최대 재귀 깊이 제한)
3. **[중복 계산 오버헤드]**: 동일 하위 문제를 반복 호출하여 지수 시간($2^n$)이 발생하는 경우 (예: 피보나치)
   - **개선방안**: 동적 계획법($DP$)의 메모이제이션($Memoization$)을 적용하여 이미 계산된 결과($Sub$-$problem$ $solution$)를 캐싱함 (확인: 시간 복잡도 하락폭)

### 2. 리얼월드 트러블슈팅 ($Real$-$world$ $Troubleshooting$)
- **상황**: 대규모 데이터 정렬($Quick$ $Sort$) 중 피벗($Pivot$) 선택 실패로 재귀 트리가 한쪽으로 치우쳐 성능이 $O(n^2)$으로 급락하고 스택 오버플로우 발생
- **해결**: 랜덤 피벗 선택($Randomized$) 또는 $Median$-$of$-$three$ 기법을 도입하여 분할 균형($b \approx 2$)을 강제함

## Ⅴ. 실무 적용 사례

| 적용 알고리즘 | 재귀식 ($T(n) = aT(n/b) + f(n)$) | 복잡도 결과 | 분석 근거 |
|:---|:---|:---|:---|
| **이진 탐색** | $T(n) = T(n/2) + O(1)$ | $O(\log n)$ | Case 2 ($a=1, b=2, \log_2 1 = 0$) |
| **병합 정렬** | $T(n) = 2T(n/2) + O(n)$ | $O(n \log n)$ | Case 2 ($a=2, b=2, \log_2 2 = 1$) |
| **$Strassen$ 행렬곱** | $T(n) = 7T(n/2) + O(n^2)$ | $O(n^{2.81})$ | Case 1 ($a=7, b=2, \log_2 7 \approx 2.81$) |

## Ⅵ. 결론

재귀 알고리즘은 복잡한 논리를 단순하게 표현하는 소프트웨어 공학의 '추상화'를 상징하며, 마스터 정리는 이를 정량화하는 '논리적 자'임. 최근에는 대규모 데이터 처리를 위해 하드웨어 병렬성($Multi$-$core$)을 고려한 병렬 재귀($Parallel$ $Recursion$) 분석으로 개념이 확장되고 있음. 기술사는 알고리즘 설계 시 복잡도의 상한선($Big$-$O$)뿐 아니라 호출 깊이와 메모리 비용을 동시에 고려하는 균형 잡힌 시각을 가져야 함.
