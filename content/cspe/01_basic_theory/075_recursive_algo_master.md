## 미리 알고가기

- 점화식($Recurrence$ $Relation$): 수열의 항 사이의 관계를 나타내는 수식으로, 알고리즘 분석에서는 입력 크기에 따른 시간 복잡도 함수를 재귀적으로 기술함
- 분할 정복($Divide$ $and$ $Conquer$): 문제를 직접 해결하기 쉬운 작은 단위로 쪼갠 뒤(Divide), 각각을 해결하고(Conquer), 결과를 융합(Combine)하여 본래의 문제를 푸는 전략임
- 호출 스택($Call$ $Stack$): 함수가 호출될 때 복귀 주소와 지역 변수를 임시로 보관하는 메모리 영역으로, 재귀 호출 시 프레임이 계속 쌓임
- 꼬리 재귀($Tail$ $Recursion$): 함수의 맨 마지막 명령어로 재귀 호출만 남겨두어, 컴파일러가 추가 스택 프레임 없이 루프 형태로 최적화할 수 있도록 설계하는 기법임

## Ⅰ. 개요

- **정의/개념**: 재귀 알고리즘은 하나의 문제를 동일한 구조의 더 작은 하위 문제로 분할하여 자기 자신을 호출해 풀어나가는 방식이며, 마스터 정리는 특정 형태를 띤 재귀식의 시간 복잡도를 단순한 비교 연산만으로 즉각 판정해 주는 강력한 수학적 도구임
- **배경/필요성**: 병합 정렬, 이진 탐색 등 분할 정복 모델의 성능(시간 복잡도)을 일일이 재귀 트리나 점화식 전개법으로 유도하면 계산 오차와 시간이 많이 소요되므로, 이를 정형화하여 고속 검증하기 위해 고안됨

## Ⅱ. 특징

- 마스터 정리는 $T(n) = aT(n/b) + f(n)$ 형태의 점화식에 대해서만 적용 가능하며, 분할 속도와 하위 문제 개수의 로그 스케일 성능($n^{\log_b a}$)과 결합 비용($f(n)$)의 성장 속도를 직접 비교함
- 재귀 호출은 코드의 논리적 가독성과 정밀함을 극대화해 주지만, 기계 레벨에서는 매번 함수 복귀 주소와 레지스터 상태를 호출 스택에 push/pop 해야 하므로 오버헤드가 발생함
- 재귀 깊이($Recursion$ $Depth$)가 메모리 한계를 초과할 경우 프로그램이 즉각 비정상 종료(Stack Overflow)하므로 반드시 한계 깊이를 설계해야 함

## Ⅲ. 마스터 정리(Master Theorem)의 3가지 케이스

$$T(n) = aT(n/b) + f(n) \quad (a \ge 1, b > 1)$$

| 조건 비교 | 해당 케이스 | 최종 시간 복잡도 $T(n)$ | 의미 요약 |
|:---|:---|:---|:---|
| $f(n) = O(n^{\log_b a - \epsilon})$ | **Case 1** (하위 문제 연산 지배) | $\Theta(n^{\log_b a})$ | 분할된 부분 문제들을 해결하는 비용($a$)이 결합하는 비용($f$)보다 더 큼 |
| $f(n) = \Theta(n^{\log_b a})$ | **Case 2** (연산과 결합의 균형) | $\Theta(n^{\log_b a} \log n)$ | 부분 문제를 푸는 속도와 결합하는 속도가 완벽히 균형을 이룸 (병합 정렬 등) |
| $f(n) = \Omega(n^{\log_b a + \epsilon})$ | **Case 3** (결합 및 분할 연산 지배) | $\Theta(f(n))$ | 결합 및 분할하는 과정의 연산량($f$)이 부분 문제를 해결하는 비용보다 지배적으로 큼 |

*단, Case 3의 경우 규칙성 조건($af(n/b) \le cf(n)$, $c < 1$)을 만족해야 함.*

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기저 조건 ($Base$ $Case$) | 더 이상 재귀 호출을 수행하지 않고 직접 답을 반환하는 재귀 탈출구임 |
| 분할 횟수 ($a$) | 하나의 큰 문제로부터 쪼개지는 동일한 하위 문제들의 총개수임 |
| 축소 비율 ($b$) | 원래 문제 대비 하위 문제의 데이터 입력 크기 감소비(예: 반으로 쪼개면 $b=2$)임 |
| 병합 비용 ($f(n)$) | 하위 문제들의 해답을 취합하여 원래의 답으로 재구성하는 부가적 시간 복잡도임 |

```text
[ 재귀 알고리즘 동작 템플릿 ]
function recursiveSolve(input) {
  if (input is small enough) return directSolve(input); // 1. Base Case (종료 조건)
  splitInputs = divide(input);                         // 2. Divide
  subSolutions = [recursiveSolve(i) for i in split];   // 3. Conquer (재귀 호출)
  return combine(subSolutions);                        // 4. Combine (결합 단계)
}
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 기저조건 확인| --> | 하위문제 분할| --> | 부분 결과반환| --> | 최종결과 결합|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **기저 확인** — 입력이 충분히 작아졌는지 확인하여 기저 조건에 도달했다면 직접 상수 시간 $O(1)$ 연산을 통해 해답을 즉시 반환함
2. **분할/재귀** — 문제가 클 경우, 변수들을 균등하게 $b$ 비율로 쪼개고 각각에 대해 동일한 자기 자신 함수를 $a$번 호출함
3. **스택 해제** — 기저 도달 후 역순으로 호출 스택의 프레임이 해제되면서, 계산 결과물들이 메모리 스택 위로 반환되기 시작함
4. **결합 연산** — 반환된 하위 해답들을 $f(n)$의 자원을 소모하며 최종 솔루션으로 조립 및 상위 층으로 재전달함

## Ⅵ. 실무 적용 및 유의점

1. 마스터 정리는 부분 문제의 크기가 균등하게 쪼개지는 경우(예: $n/2$)에만 적용되며, 피보나치 수열($T(n) = T(n-1) + T(n-2)$)처럼 불균등하거나 선형 축소 구조를 갖는 경우에는 적용할 수 없으므로 '재귀 트리법'이나 'Akra-Bazzi 정리'를 사용해야 함
2. 메모리가 극도로 제약된 시스템(예: 임베디드 디바이스)에서 재귀 알고리즘을 사용하면 스택 오버플로우가 날 우려가 있으므로, '꼬리 재귀 최적화'를 적용하거나 스택 자료구조를 수동 제어하는 '반복문($Iterative$ $Loop$)' 형태로 코드를 리팩터링해야 함

## Ⅶ. 결론

- 재귀 알고리즘은 복잡한 논리를 단순한 기호의 반복으로 환원하는 수학적 미학의 핵심이며, 설계자는 실행 시간의 오차가 지연시간으로 전이되는 것을 막기 위해 마스터 정리를 통한 최적 시간 평가와 메모리 한계 설계를 필히 구축해야 함
