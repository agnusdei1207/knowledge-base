## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 문제를 하위 문제로 분할하여 해결하는 방식(재귀)과, 이러한 분할 정복 알고리즘의 시간 복잡도를 도출하는 공식(마스터 정리)임. |
| 배경/필요성 | 복잡한 알고리즘(병합 정렬, 트리 탐색 등)의 구조를 단순화하고 점근적 실행 시간을 명확히 산정하기 위함. |
| 출제 의도 | 재귀의 콜 스택 오버헤드 한계 인식 및 마스터 정리를 이용한 알고리즘 복잡도 계산 능력 평가. |

## Ⅱ. 구성요소
```text
+-----------+    +-----------+    +-----------+
| Base Case | -> | Recur Call| -> | Recur Eq  |
+-----------+    +-----------+    +-----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 기저 조건(Base Case) | 재귀 호출을 중단하고 직접 해를 반환하는 최소 단위 조건 | 탈출구 |
| 재귀 호출(Recursive) | 문제 크기를 축소하여 자기 자신을 다시 호출하는 단계 | 거울 방 |
| 점화식(Recurrence) | $T(n) = aT(n/b) + f(n)$ 형태로 복잡도를 나타낸 수식 | 점화 공식 |

> 요약: 문제를 기저 조건에 닿을 때까지 분할(재귀)하고, 마스터 정리 점화식을 통해 계산 비용을 산출함.

## Ⅲ. 절차
```text
+----------+   +----------+   +----------+   +----------+
| Def Prob |-> | Split Sub|-> | Hit Base |-> | Merge All|
+----------+   +----------+   +----------+   +----------+
```
1. 문제 정의: 전체 문제를 해결하기 위한 재귀 함수 형태와 기저 조건을 명세함.
2. 하위 분할: $n$ 크기의 문제를 $n/b$ 크기의 하위 문제로 분할하며 재귀 호출함.
3. 기저 접근: 문제 크기가 최소가 되어 기저 조건을 만나면 반환 시작함.
4. 병합 단계: 하위 문제의 결과를 $f(n)$ 비용으로 병합하여 최종 답을 완성함.

> 요약: 문제를 반복적으로 분할한 뒤, 기저 조건부터 역방향으로 결과를 취합하고 복잡도를 계산함.

## Ⅳ. 문제점
- 재귀 호출 깊이가 과도할 경우 함수 콜 스택(Call Stack) 누적으로 인한 메모리 오버플로우 발생
- 동일한 하위 문제가 반복되는 구조(예: 피보나치)일 경우 알고리즘 수행 시간이 지수적으로 폭증함
- 대규모 분할 정복 문제 처리 시 단일 코어 환경에서의 물리적 성능 병목 현상 불가피

## Ⅴ. 개선방안
- [단기] 기저 조건 검증 로직을 견고히 하고 동적 계획법(Memoization)으로 중복 연산 방지
- [중기] 꼬리 재귀(Tail Recursion) 최적화 지원 컴파일러를 활용하여 반복문과 동일한 효율성 달성
- [장기] 마스터 정리로 도출된 복잡도를 바탕으로 다중 노드 분산 처리 병렬 알고리즘 설계 도입

## Ⅵ. 전망
- 자료구조(트리, 그래프) 탐색 및 현대 빅데이터 분산 처리(MapReduce)의 근본적인 문제 해결 패러다임임.
