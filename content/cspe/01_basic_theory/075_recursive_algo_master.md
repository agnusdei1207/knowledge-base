## Ⅰ. 개요
- **정의**: 문제를 동일 구조의 하위 문제로 분할·해결하는 재귀와, 그 시간 복잡도를 정형 산출하는 마스터 정리임
- **배경/필요성**: 분할 정복 알고리즘의 정확한 복잡도 산정 없이는 알고리즘 선택·비교가 불가능
- **비유**: 큰 상자를 작은 상자로 계속 쪼개고, 쪼개는 비용을 공식 한 줄로 계산하는 체계

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 재귀의 구조적 원리 | 기저 조건 + 축소 호출 + 병합 | 반복문 변환 가능성 언급 필수 |
| 마스터 정리 3가지 경우 | T(n)=aT(n/b)+f(n)의 Case 1·2·3 판별 | 적용 불가 조건(비균등 분할 등) 명시 |

> 요약: 재귀로 문제를 분할·정복하고, 마스터 정리 T(n)=aT(n/b)+f(n)으로 복잡도를 O 표기로 산출하는 체계임

## Ⅱ. 구성요소
```text
+----------+     +----------+     +----------+
| Base     | --> | Recursive| --> | Recurrence|
| Case     |     | Call     |     | Relation  |
| (Return) |     | (Divide) |     | T(n)=...  |
+----------+     +----------+     +----------+
                                       |
                                  +----+----+
                                  | Master  |
                                  | Theorem |
                                  +---------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 기저 조건 | 재귀 종료 지점, n≤c일 때 상수 시간 O(1)로 직접 해 반환 | 마트료시카 최소 인형 |
| 재귀 호출 | n을 n/b로 축소하여 a번 자기 호출, 문제를 하위로 위임 | 거울 속 거울 |
| 점화식 | T(n)=aT(n/b)+f(n), 분할 횟수·크기·병합 비용을 정량화한 수식 | 비용 산출 공식 |
| 마스터 정리 | log_b(a)와 f(n)의 차수를 비교하여 3가지 Case로 O 표기 결정 | 자동 판별기 |

> 요약: 기저 조건으로 종료를 보장하고, 점화식을 세워 마스터 정리의 3-Case로 복잡도를 판별함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| Define   | -> | Divide   | -> | Conquer  | -> | Analyze  |
| f(n),Base|    | n -> n/b |    | Merge a  |    | Master   |
+----------+    +----------+    +----------+    +----------+
```

1. **문제 정의** — 입력 크기 n, 기저 조건, 병합 함수 f(n)을 명세함
2. **분할(Divide)** — n을 b등분하여 a개의 하위 문제(크기 n/b)를 생성, 재귀 호출함
3. **정복·병합(Conquer)** — 기저 도달 후 반환값을 f(n) 비용으로 병합하여 상위 해 구성함
4. **복잡도 분석** — 점화식 T(n)=aT(n/b)+f(n) 수립 후 마스터 정리 적용:
   - Case 1: f(n)=O(n^(log_b(a)-ε)) → T(n)=Θ(n^log_b(a))
   - Case 2: f(n)=Θ(n^log_b(a)) → T(n)=Θ(n^log_b(a) · log n)
   - Case 3: f(n)=Ω(n^(log_b(a)+ε)) → T(n)=Θ(f(n))

> 요약: 문제 정의 → 분할 → 병합 → 마스터 정리 3-Case 판별의 4단계 분석 절차임

## Ⅳ. 문제점
- [스택 오버플로우]: 재귀 깊이가 O(n)급일 때 콜 스택 메모리 초과 발생 (기본 스택 1~8MB)
- [중복 계산]: 하위 문제 중복 시(피보나치 등) 호출 횟수가 O(2^n)으로 지수 폭증
- [마스터 정리 미적용]: 비균등 분할(T(n)=T(n/3)+T(2n/3)+n) 등 정규 형태 불일치 시 정리 적용 불가

> 요약: 스택 한계, 중복 호출 폭증, 마스터 정리 적용 범위 제한이 3대 한계임

## Ⅴ. 개선방안
1. 단기: 꼬리 재귀(Tail Recursion) 변환 또는 명시적 스택 자료구조로 콜 스택 오버플로우 방지
2. 중기: 메모이제이션/동적 계획법(DP)으로 중복 하위 문제를 O(n) 테이블에 캐싱, 지수→다항 시간 전환
3. 장기: Akra-Bazzi 정리 등 확장 도구를 활용하여 비균등 분할 점화식의 복잡도까지 정형 분석

- [스택 크기 부족]: 재귀 깊이 10만+ 시 → ulimit 조정 또는 반복 변환 (지표: 최대 재귀 깊이 ≤ O(log n))

> 요약: 꼬리 재귀 → 메모이제이션 → 확장 정리 순으로 실행 안정성과 분석 범위를 확대함

## Ⅵ. 전망
- 향후 발전 방향: 분산 환경(MapReduce, Spark)에서 분할 정복 패러다임이 대규모 데이터 병렬 처리의 기본 모델로 확장
- 기술사적 판단: 알고리즘 복잡도 분석의 핵심 도구로서 마스터 정리는 CS 기초 교육·시험의 필수 역량
- 기술사 제언: 재귀 알고리즘 설계 시 반드시 점화식을 수립하고 마스터 정리 적용 가능 여부를 선검증하여 복잡도 보장 필요
