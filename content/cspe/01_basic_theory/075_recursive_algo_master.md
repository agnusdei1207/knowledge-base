## 미리 알고가기

- 재귀: 함수가 자기 자신을 호출해 같은 구조의 하위 문제를 해결하는 방식임
- 기저 조건: 더 이상 재귀 호출하지 않고 바로 답을 반환하는 종료 조건임
- 점화식: 입력 크기에 따른 실행 시간을 자기 자신과 추가 비용의 식으로 표현한 것임
- 분할 정복: 문제를 나누고 하위 문제를 해결한 뒤 결과를 결합하는 알고리즘 설계 전략임
- 마스터 정리: `T(n)=aT(n/b)+f(n)` 형태 점화식의 복잡도를 차수 비교로 구하는 정리임
- 호출 스택: 재귀 호출의 지역 변수와 반환 지점을 저장하는 런타임 메모리 구조임

## Ⅰ. 개요

- **정의**: 재귀 알고리즘은 문제를 같은 형태의 더 작은 하위 문제로 줄여 해결하고, 마스터 정리는 균등 분할 점화식에서 하위 문제 수·크기·병합 비용을 기준으로 시간 복잡도를 판정하는 분석 도구임. 분할 정복 알고리즘의 실행 시간과 확장성을 빠르게 판단하기 위해 사용함
- **배경/필요성**: 병합 정렬, 이진 탐색, 분할 정복 최적화처럼 반복 구조가 하위 문제 형태로 표현될 때 직관적 설계와 복잡도 분석이 필요함
- **비유**: 큰 업무를 같은 방식의 작은 업무로 계속 쪼개고, 각 단계의 쪼개기·합치기 비용을 공식으로 계산하는 방식과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 재귀 구조 설명 | 기저 조건, 재귀 호출, 병합 | 종료 조건 누락 |
| 마스터 정리 적용 | `a`, `b`, `f(n)`, 3가지 case | 적용 불가 점화식에 억지 적용 |

> 요약: 재귀는 문제 해결 구조이고 마스터 정리는 그 구조가 균등 분할일 때 복잡도를 빠르게 판정하는 기준임

## Ⅱ. 특징/비교

| 판단 기준 | 반복 알고리즘 | 재귀 알고리즘 | 재귀+마스터 정리 |
|:---|:---|:---|:---|
| 표현 방식 | 루프와 상태 변수를 직접 관리함 | 하위 문제 호출과 기저 조건으로 표현함 | 호출 구조를 점화식으로 표현함 |
| 장점 | 스택 비용이 적고 실행 흐름이 명확함 | 분할 구조와 트리 구조 표현이 자연스러움 | 복잡도 산정이 빠르고 표준화됨 |
| 위험 | 상태 관리가 복잡해질 수 있음 | 스택 오버플로우와 중복 호출 위험이 있음 | 정규 형태가 아니면 적용할 수 없음 |
| 선택 기준 | 단순 반복·성능 민감 | 트리·분할·백트래킹 구조 | 균등 분할 정복 복잡도 분석 |

> 요약: 재귀는 구조 표현력이 강하지만 실행 안정성은 별도 관리가 필요하고, 마스터 정리는 적용 조건이 맞을 때만 사용해야 함

- **Case 1**: 하위 문제 비용이 병합 비용보다 지배적이면 `T(n)=Θ(n^log_b a)`임
- **Case 2**: 하위 문제 비용과 병합 비용 차수가 같으면 로그 인자가 추가됨
- **Case 3**: 병합 비용이 지배적이고 정규성 조건을 만족하면 `T(n)=Θ(f(n))`임

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Problem n   | ---> | Base Case   | ---> | Return      |
| input       |      | n <= c      |      | direct ans  |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Recursive   | ---> | Combine     | ---> | Recurrence  |
| Calls a,b   |      | Cost f(n)   |      | T(n)=...    |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 크기 `n` | 알고리즘 비용을 측정할 문제 규모 기준임 | 업무량 |
| 기저 조건 | 재귀를 멈추고 상수 시간 답을 반환하는 조건임 | 마지막 상자 |
| 재귀 호출 | 크기 `n/b`의 하위 문제를 `a`개 호출하는 구조임 | 하청 작업 |
| 병합 비용 `f(n)` | 하위 문제 결과를 결합하거나 분할하는 데 드는 추가 비용임 | 조립 비용 |
| 점화식 | 호출 수, 크기, 병합 비용을 하나의 시간 함수로 표현함 | 비용 계산서 |

> 요약: 재귀 분석은 입력 규모, 종료 조건, 호출 수·크기, 병합 비용을 점화식으로 연결해 수행함

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Define    | --> | Recur     | --> | Build     | --> | Apply     |
| Base/f(n) |     | a, n/b    |     | T(n)      |     | Theorem   |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
termination        subproblem count    recurrence        Big-O/Theta
```

1. **문제 구조 정의**: 입력 크기, 기저 조건, 하위 문제로 줄어드는 방식, 병합 비용을 명확히 함
2. **점화식 수립**: 하위 문제 개수 `a`, 축소 비율 `b`, 추가 비용 `f(n)`을 이용해 `T(n)=aT(n/b)+f(n)` 형태를 확인함
3. **차수 비교**: `n^log_b a`와 `f(n)`의 차수를 비교해 마스터 정리 3가지 case 중 하나를 선택함
4. **적용 가능성 검증**: 비균등 분할, 중복 하위 문제, 정규성 조건 위반이면 대체 분석이나 DP를 검토함

> 요약: 마스터 정리는 점화식을 세운 뒤 하위 문제 비용과 병합 비용의 차수를 비교하고 적용 조건까지 확인해야 함

## Ⅴ. 문제점

- **P1 스택 오버플로우**: 재귀 깊이가 입력 크기에 비례하면 호출 스택이 초과되어 실행 중단이 발생할 수 있음
- **P2 중복 계산 폭증**: 피보나치처럼 같은 하위 문제를 반복 호출하면 시간 복잡도가 지수적으로 증가함
- **P3 마스터 정리 적용 한계**: 비균등 분할, 여러 크기의 하위 문제, 비다항 추가 비용은 표준 정리로 바로 풀 수 없음

> 요약: 재귀 알고리즘은 종료·스택·중복 문제를 관리해야 하며, 복잡도 분석은 정리 적용 조건을 반드시 확인해야 함

## Ⅵ. 개선방안

- **P1 대응**: 꼬리 재귀 최적화, 명시적 스택, 반복문 변환으로 호출 깊이를 통제함 (확인: 최대 재귀 깊이, 스택 사용량)
- **P2 대응**: 메모이제이션이나 동적 계획법으로 이미 계산한 하위 문제 결과를 저장함 (확인: 중복 호출 수, 시간 복잡도)
- **P3 대응**: 재귀 트리, 치환법, Akra-Bazzi 정리 등 대체 분석 방법을 사용함 (확인: 점화식 형태와 조건 충족 여부)

> 요약: 실행 문제는 반복·캐싱으로 줄이고, 분석 문제는 점화식 형태에 맞는 도구를 선택해 해결함

## Ⅶ. 전망

- **향후 발전 방향**: 재귀와 분할 정복은 병렬 알고리즘, MapReduce, divide-and-conquer DP 등 대규모 처리 패턴으로 계속 확장될 전망임
- **기술사적 판단**: 알고리즘 선택 시 구현의 직관성만 아니라 스택 안정성과 복잡도 보장을 함께 평가해야 함
- **기술사 제언**: 답안에서는 재귀 코드보다 기저 조건, 점화식, 마스터 정리 적용 조건을 중심으로 서술해야 함
