# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 수많은 결정 트리(Decision Tree)를 다르게 생성하여 '숲(Forest)'을 이룬 뒤, 이들의 예측을 다수결로 합쳐 결론을 내리는 앙상블(Ensemble) 알고리즘.
- **왜 필요한가**: 결정 트리 1개는 훈련 데이터의 사소한 노이즈까지 암기하여 실전에서 틀려버리는 과적합(Overfitting)에 매우 취약하고 불안정하기 때문.
- **핵심 직관**: 1명의 천재(깊은 트리 1개)는 편견에 빠져 치명적 실수를 할 수 있지만, 100명의 평범한 전문가(랜덤 포레스트)가 각자 조금씩 다른 시각으로 분석해 다수결(투표)을 하면 가장 합리적인 결론이 나온다는 '집단 지성'.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 배깅 (Bagging) | Bootstrap Aggregating. 원본 데이터에서 복원 추출로 여러 개의 서브 데이터셋을 만들어 각각 모델을 훈련시키는 기법 | 100명의 전문가에게 사건 파일 중 일부만 무작위로 복사해 나눠주기 |
| 무작위 특성 선택 (Random Feature) | 트리가 분기할 때 모든 피처(변수)를 보지 않고, 랜덤으로 뽑은 일부 피처만 고려하여 트리를 성장시키는 것 | 어떤 전문가는 지문과 혈흔만, 어떤 전문가는 족적과 흉기만 보고 판단하게 강제함 |
| OOB (Out-Of-Bag) 오차 | 배깅 과정에서 뽑히지 않고 남은(36.8%) 데이터로 트리의 성능을 자체 평가하는 지표 | 시험 문제를 만들고 남은 문제지로 치르는 자체 모의고사 |

## 깊이 이해
- **배경·문제의식**: 배깅(Bagging)으로 여러 트리를 만들어도, 모든 트리가 '결정적이고 가장 강력한 변수(예: 소득)'만 쳐다보면 결국 100개의 트리가 다 똑같이 생겨 앙상블의 의미(다양성)가 퇴색됨.
- **작동 원리**: 이 문제를 해결하기 위해 '무작위 특성 선택'을 도입함. 즉 노드를 분할할 때 100개의 변수 중 루트 단위(√100 = 10개)만 무작위로 뽑아 그 안에서 최적의 분할을 찾음. 이렇게 하면 억지로 다른 변수를 사용하는 '다양한 관점의 개성 있는 트리들'이 자라남. 트리들의 편향(Bias)은 유지되면서, 앙상블 시 분산(Variance)이 크게 줄어들어 과적합이 마법처럼 사라짐.
- **구체 예시**: 병원에서 100명의 의사가 환자를 진단함. A의사는 혈압 위주로, B의사는 간수치 위주로 얕게 진단함. 이들의 결과를 다수결 투표(Hard Voting)하면 단일 초정밀 AI 모델보다 훨씬 안정적이고 정확한 진단이 나옴.
- **흔한 오해·주의점**: 무작위성 때문에 결정 트리의 최대 장점이었던 "완벽한 설명력(가지가 어떻게 뻗었는지 눈으로 보기)"은 상실함(블랙박스화). 대신 변수 중요도(Feature Importance) 점수를 통해 어떤 변수가 중요한지 간접적으로 파악함.

## 연결 개념
- **부스팅 (Boosting)**: 배깅이 모델들을 독립적/병렬로 만드는 것이라면, 부스팅은 앞 모델이 틀린 오답을 뒷 모델이 집중해서 고치도록 순차적/직렬로 학습하는 앙상블 기법 (XGBoost, LightGBM).

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 데이터와 피처의 무작위 추출(배깅+랜덤 피처) 기반 결정 트리 다수결 앙상블 모델
> 2. **가치**: 개별 트리의 높은 분산(과적합)을 집단 투표로 상쇄하여 압도적 안정성 및 일반화 성능 확보
> 3. **판단 포인트**: 별도의 검증 세트 없이 OOB(Out-of-Bag) 데이터로 자체 검증이 가능한 정형 데이터 분석의 기준(Baseline) 모델

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 앙상블 기법의 분산 감소 원리와 무작위성 이해 | 배깅(Bagging), Random Feature Selection, 다수결(Voting), OOB 에러 | 배깅만 언급하고 '특성(Feature) 무작위 선택'의 비상관화 효과를 누락 |

> 요약: 무작위 샘플링과 무작위 변수 선택으로 상호 독립적인 다수의 트리를 생성하고, 이들을 결합하여 과적합을 방지하는 앙상블 기법

---

## Ⅰ. 개요 및 필요성
- 개요: 다수의 결정 트리(Decision Tree)를 훈련시키고 이들의 예측을 취합(투표 또는 평균)하여 최종 결과를 도출하는 배깅(Bagging) 기반 앙상블 알고리즘
- 배경: 단일 결정 트리는 훈련 데이터의 작은 노이즈에도 분기 구조가 급변하여 과적합(High Variance)에 빠지는 치명적 결함 노출
- 필요성: 모델의 분산(Variance) 감소, 이상치 조기 극복, 과도한 하이퍼파라미터 튜닝 없이도 안정적인 고성능 확보(Robustness) 필요

---

## Ⅱ. 구조 및 구성요소

```text
원본 데이터 -> [ 부트스트랩 샘플링 (복원 추출) ] -> N개의 서브 데이터셋 (Bag) 생성
                     |
               [ 트리 성장 시 무작위 속성(Feature) 선택 분기 ] -> 개성 있는 N개의 결정 트리 병렬 성장
                     |
               [ 결합 (Aggregation) ] -> (분류: 다수결 / 회귀: 평균) -> 최종 예측
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 부트스트랩 (Bootstrap) | 원본 데이터에서 크기가 동일하게 복원 추출된 샘플 데이터셋 | 한 샘플이 여러 번 뽑히거나 한 번도 안 뽑힐 수 있음 |
| 무작위 특성 선택 | 노드 분기 시 전체 피처(p) 대신 일부(√p)만 랜덤으로 추출하여 분할 | 트리 간의 상관관계를 낮춰(De-correlation) 다양성 확보 |
| 앙상블 집계 (Aggregation) | N개의 독립적 예측값을 하나로 합쳐 최종 결론 도출 | 하드 보팅(분류), 소프트 보팅, 평균(회귀) 적용 |
| OOB (Out-Of-Bag) | 복원 추출 시 선택되지 않은 잔여 데이터(~36.8%)로 자체 평가 | 별도의 검증 세트(Validation Set) 구축 비용 절감 |

> 요약: 행(데이터)과 열(변수)에 모두 무작위성을 부여하여 독립된 트리를 만들고 병렬로 투표하는 구조

---

## Ⅲ. 동작원리 및 흐름도

```text
부트스트랩 샘플링 -> 루트/피처 제한 분기 반복 -> 나무 성장(가지치기 X) -> 병렬 트리 결합 -> 변수 중요도 산출
```

- 1단계 [샘플 무작위 추출]: N개의 원본 데이터세트에서 N번 복원 추출하여 트리 개수만큼의 부트스트랩 데이터 세트 생성
- 2단계 [피처 비상관화 분기]: 각 노드를 쪼갤 때, 전체 피처 중 랜덤하게 지정된 개수(주로 제곱근)만 대상으로 정보 획득량을 계산하여 최적 분할
- 3단계 [최대 성장 유도]: 과적합을 두려워하지 않고 각 트리가 최대 깊이(Max Depth)까지 제한 없이 끝까지 자라게 방치(편향 최소화)
- 4단계 [예측 및 중요도 산출]: 병렬로 도출된 결과를 집계하여 최종 예측을 수행하고, 분할 시 불순도를 가장 많이 낮춘 변수들의 기여도(Feature Importance) 도출

> 요약: 무작위성으로 개별 트리의 다양성을 극대화한 뒤, 숲 전체의 평균화로 과적합 오차를 상쇄시킴

---

## Ⅳ. 특징
- [탁월한 범용 성능]: 정형(Tabular) 데이터에 한해 튜닝 없이 기본(Default) 파라미터만으로도 딥러닝에 필적하는 강력한 베이스라인(Baseline) 성능 제공
- [병렬 처리 극대화]: 각 트리는 서로 참조할 필요 없이 완전히 독립적으로 자라므로 멀티 코어 환경에서 분산/병렬 학습 최적화
- [블랙박스화 한계]: 트리가 수백 개 융합되면서 개별 룰 경로 추적이 불가능해져, 결정 트리의 가장 큰 장점인 직관적 설명력(XAI) 상실
- [메모리/용량 과다]: 거대한 트리를 수백~수천 개 메모리에 올려야 하므로 모바일이나 엣지 디바이스 등 초경량 추론 환경에는 부적합

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단일 결정 트리 | 랜덤 포레스트 (Bagging) | Gradient Boosting (GBM/XGBoost) |
|:---|:---|:---|:---|
| 과적합 제어 원리 | 얕게 만들기 (가지치기) | 깊게 만들고 다수결로 상쇄 | 얕은 트리를 순차적 오차 보정 |
| 학습 구조 및 속도 | 순차적(단일) / 매우 빠름 | 병렬 앙상블 / 학습·추론 빠름 | 직렬 앙상블 / 학습 느림(병목) |
| 오류(오차) 해결 | 편향, 분산 모두 높음 | 분산(Variance)을 급격히 감소 | 편향(Bias)을 집중적으로 감소 |

**리스크·대응:**
- [설명력 상실 병목]: 현업 부서에서 "왜 그런 예측이 나왔나" 요구 시 블랙박스 한계 → SHAP, LIME 등 사후 설명 가능 AI(XAI) 툴과 결합 (지표: 국소적 해석력 확보)
- [희소 데이터 취약]: 텍스트나 고차원 희소(Sparse) 행렬 데이터 주입 시 성능 급락 → 해당 데이터는 나이브 베이즈나 선형 SVM으로 우회 (지표: F1-Score 하락 방어)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. [베이스라인(Baseline) 모델링]: 신규 머신러닝 프로젝트 착수 시, 복잡한 딥러닝 전 데이터의 유효성을 검증하기 위한 첫 번째 비교군 표준 모델로 투입
2. [변수 중요도(Feature Importance) 추출]: 수백 개의 피처 중 타겟 예측에 기여한 불순도 감소 누적액을 랭킹화하여, 상위 20개 핵심 변수만 남기는 차원 축소 툴로 활용
3. [자체 검증 파이프라인(OOB)]: 데이터 셋이 너무 작아 Train/Test 분리 시 손실이 클 때, 버려진 데이터(OOB)로 검증(Validation)을 대체하여 학습 데이터량 보존

**결론:**
- 기술사 판단: 정형 데이터 분류/회귀 실무에서 가장 실패 확률이 낮고 신뢰도 높은 무결점 모델이나, 복잡한 인과관계 추적 시에는 단일 트리 혹은 SHAP 연동이 필수적임
- 향후 방향: 최근 성능의 한계점(편향 축소 한계)으로 인해 캐글 등 경쟁 환경에서는 XGBoost, LightGBM 등 부스팅(Boosting) 계열 트리 연합체로 헤게모니가 이동함
