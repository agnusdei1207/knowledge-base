# 랜덤 포레스트 (Random Forest)

## 1. 개요

- **정의/개념**: 랜덤 포레스트는 여러 결정 트리를 bootstrap 샘플과 무작위 feature subset으로 학습한 뒤 투표 또는 평균으로 예측하는 앙상블 모델이다.
- **배경/필요성**: 단일 결정 트리는 해석성은 높지만 분산이 커서 데이터 변화에 민감하므로, 여러 트리를 결합해 일반화 성능과 안정성을 높일 필요가 있다.

랜덤 포레스트의 핵심은 트리 하나를 강하게 만드는 것이 아니라 서로 다른 트리를 많이 만들어 분산을 줄이는 것이다.

## 2. 특징 및 비교

| 구분 | 결정 트리 | 랜덤 포레스트 | Gradient Boosting |
|---|---|---|---|
| 학습 방식 | 단일 트리 | 병렬 다수 트리 | 순차적 오류 보정 |
| 강점 | 해석 쉬움 | 안정성, 과적합 완화 | 높은 예측 성능 |
| 약점 | 과적합 | 모델 크기, 해석성 저하 | 튜닝 민감 |
| 결합 방식 | 없음 | bagging | boosting |

선택 기준은 정확도, 해석성, 데이터 크기, feature 중요도 활용, 추론 비용이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Bootstrap Sample | 복원 추출 학습 데이터 | 트리 다양성 |
| Random Feature Subset | 분할 후보 feature 제한 | 상관 감소 |
| Decision Tree | 개별 약한 모델 | base learner |
| Voting/Averaging | 분류 투표·회귀 평균 | 최종 예측 |
| OOB Error | 선택되지 않은 샘플로 평가 | 내부 검증 |

```text
데이터 -> bootstrap 샘플들 -> 여러 트리 학습 -> 투표/평균 -> 예측
```

다양한 트리가 독립적으로 오류를 만들수록 결합 효과가 커지므로, 무작위성이 성능 안정화의 근거이다.

## 4. 문제점 및 개선방안

1. **해석성 저하**
   - 단일 트리보다 전체 결정 과정을 설명하기 어렵다.
   - **개선방안**: feature importance, permutation importance, SHAP을 활용한다.

2. **추론 비용 증가**
   - 트리 수가 많으면 메모리와 지연 시간이 증가한다.
   - **개선방안**: 트리 수·깊이 제한, 모델 압축, latency 기준 튜닝을 적용한다.

3. **상관 높은 트리**
   - 트리들이 비슷하면 앙상블 이득이 줄어든다.
   - **개선방안**: feature subset 크기 조정, bootstrap 비율 조정, 데이터 다양화가 필요하다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 신용 평가 | 다양한 고객 feature로 안정적 분류 모델 구성 | AUC, KS |
| 제조 품질 | 센서 feature 기반 불량 예측 | recall, false alarm |
| 변수 중요도 분석 | feature importance로 영향 요인 파악 | 중요도 안정성 |

## 6. 결론

랜덤 포레스트는 결정 트리의 분산 문제를 bagging과 feature 무작위성으로 완화하는 앙상블 모델이다. 트리 다양성, 결합 방식, 해석성, 추론 비용을 함께 판단해야 단일 트리와 boosting 계열 사이의 선택 기준이 분명해진다.
