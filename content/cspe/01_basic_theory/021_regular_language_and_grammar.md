# 📖 【암기용】 개념 완전 이해

> 목적: 정규 언어와 문법을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **정규 언어(Regular Language)**는 촘스키 위계에서 가장 단순한 언어(Type 3)로, 유한 오토마타(FA)로 인식 가능한 언어 집합이다.
- **왜 필요한가**: 컴파일러의 어휘 분석(Lexical Analysis) 단계에서 소스 코드의 문자열을 의미 있는 토큰(Token)으로 분리할 때, 빠르고 결정론적인 패턴 매칭이 필요하기 때문이다.
- **핵심 직관**: 기억력이 없는 기계(상태만 있음)가 규칙적인 패턴(예: `a` 뒤에 `b`가 0번 이상 온다)을 읽고 맞는지 틀린지 판별하는 규칙이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 촘스키 위계 Type 3 | 가장 제약이 강하고 단순한 문법 체계 | 가장 엄격한 맞춤법 검사기 |
| 정규 표현식 (Regex) | 정규 언어를 대수적으로 표현하는 식 | 검색할 때 쓰는 `[A-Z]+[0-9]*` |
| 유한 오토마타 (FA) | 정규 언어를 인식하는 추상 기계 (상태 전이) | 기억력 없이 현재 상태만 아는 자판기 |
| 생성 규칙 (Production) | 기호가 다른 기호로 대체되는 규칙 ($A \rightarrow aB$) | 단어를 만드는 조립 설명서 |

## 깊이 이해
- **배경·문제의식**: 복잡한 문맥(Context)을 이해하는 언어는 분석 비용이 높다. 변수명, 숫자, 키워드처럼 단순하고 규칙적인 문자열은 가장 가벼운 기계 모델로 빠르게 처리해야 한다.
- **작동 원리**: 정규 문법은 $A \rightarrow aB$ 또는 $A \rightarrow a$ 형태의 극도로 제한된 생성 규칙만 허용한다(우선형 기준). 이 규칙은 현재 상태($A$)에서 문자($a$)를 읽고 다음 상태($B$)로 넘어가는 유한 오토마타의 동작과 정확히 일치한다.
- **비유**: 지하철 개찰구(FA)는 '카드 태그(입력)' -> '문 열림(상태 전이)' -> '통과(완료)'라는 단순한 규칙(정규 문법)만 처리하며, 전에 몇 명이 통과했는지(기억)는 알 필요가 없다.
- **구체 예시**: 
  - 정규 표현식: `a(a|b)*` (a로 시작하는 a와 b의 문자열)
  - 정규 문법: $S \rightarrow aA$, $A \rightarrow aA | bA | \epsilon$
- **흔한 오해·주의점**: 정규 언어는 괄호의 짝 맞추기 `( ( ) )` 같은 문제를 풀 수 없다. 유한 오토마타는 지나간 괄호의 개수를 셀 메모리(스택)가 없기 때문이다. 이는 문맥 자유 언어(Type 2)의 영역이다.

## 연결 개념
- 문맥 자유 문법 (Type 2) — 구문 분석(Parsing)의 기반
- 오토마타 이론 (DFA/NFA) — 정규 언어의 인식 기계
- 컴파일러 어휘 분석기 (Lexer) — 실무 적용 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정규 언어는 촘스키 위계(Type 3) 중 가장 제한적인 언어로, 정규 표현식으로 서술되고 유한 오토마타(FA)로 인식 가능한 기호 집합이다.
> 2. **가치**: 스택 메모리 없이 유한한 상태(State) 전이만으로 패턴을 매칭하므로, O(n)의 시간 복잡도로 매우 빠른 문자열 분석이 가능하다.
> 3. **판단 포인트**: 컴파일러 설계 시 어휘 분석(토큰화)은 정규 문법으로, 구문 분석(AST 생성)은 문맥 자유 문법으로 분리하여 파싱 효율을 극대화한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 언어의 이론적 기반과 한계 이해 | 촘스키 Type 3, 정규 표현식, 유한 오토마타 연결 | 정규 언어와 문맥 자유 언어의 한계(괄호 매칭 불가 등) 누락 |
| 생성 규칙의 제약 조건 지식 | $A \rightarrow aB$ 또는 $A \rightarrow a$ 형태의 선형 생성 규칙 | 비선형 규칙($A \rightarrow aBb$) 혼용 표기 |
| 실무 응용(컴파일러) 연결 역량 | 어휘 분석기(Scanner), 토큰 생성, 렉스(Lex) | 추상적인 기호 이론으로만 서술하고 실무 적용 누락 |

> 요약: 이론적 정의(표현식·FA·생성규칙)의 등가성을 설명하고, 이것이 컴파일러의 어휘 분석에 어떻게 쓰이는지 연결해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 촘스키 언어 위계 중 제약이 가장 강한 Type 3 문법으로 생성되며, 유한 상태 기계로 판별 가능한 언어
- 배경: 프로그래밍 언어의 텍스트를 기계가 해석하려면 규칙적이고 처리 비용이 매우 낮은 수학적 모델이 필요
- 필요성: 어휘 분석 단계를 O(n) 복잡도로 처리하여, 전체 파싱 성능 저하를 방지

---

## Ⅱ. 구조 및 구성요소

```text
정규 언어의 3가지 등가 표현 구조
정규 표현식 (패턴 서술) -> 정규 문법 (생성 규칙) -> 유한 오토마타 (인식 기계)
                               |                    |
                               +-> 어휘 분석기(Lex)  +-> 토큰 스트림
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규 표현식 (Regular Expression) | 언어의 패턴을 대수적 기호(연결, 합집합, 클레이니 스타)로 서술 | 인간이 패턴을 작성하는 수단 |
| 정규 문법 (Regular Grammar) | 비단말 기호 하나가 단말 기호 하나와 결합하는 선형 규칙 정의 | $A \rightarrow aB$ (우선형), $A \rightarrow Ba$ (좌선형) |
| 유한 오토마타 (Finite Automata) | 상태와 전이 함수로 입력 문자열의 수용 여부를 판별 | DFA와 NFA는 정규 언어 인식 능력이 동일 |

> 요약: 표현식은 패턴을 정의하고, 문법은 기호를 생성하며, 오토마타는 문자열을 인식하는 동일한 언어의 세 가지 측면이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
어휘 분석기(Scanner)의 정규 언어 인식 흐름
소스 코드 입력 -> 문자 스트림 읽기 -> 정규 표현식 매칭(FA 상태 전이) -> 토큰 반환
```

- 1단계 [문자열 입력]: 소스 코드에서 의미 단위 기호(문자)를 순차적으로 입력
- 2단계 [상태 전이 처리]: 입력 문자에 따라 DFA의 현재 상태에서 다음 상태로 전이 함수 $f(Q, \Sigma) \rightarrow Q'$ 실행
- 3단계 [수용 상태 검증]: 문자열 종료 시 최종 상태가 수용 상태(Accept State) 집합에 속하는지 확인
- 4단계 [토큰 출력]: 수용 시 해당 문자열을 유효한 토큰(예: Identifier, Keyword)으로 구문 분석기에 전달

> 요약: 문자를 차례로 읽으며 기계의 상태를 전이시키고, 최종 상태 도달 여부로 패턴 일치를 판별한다.

---

## Ⅳ. 특징

- O(n) 선형 분석 속도: 백트래킹이나 스택 연산 없이, 입력 길이 n에 비례하여 1회 스캔으로 판별 완료
- 상태 메모 부재 한계: 과거의 입력 횟수나 계층적 구조를 기억할 수 없어 $a^n b^n$ 형태의 대칭 구조 판별 불가
- 클레이니 폐포(Kleene Closure) 닫힘 성질: 정규 언어 간의 합집합, 교집합, 여집합, 연결 연산 결과도 항상 정규 언어 유지

> 요약: 극도의 분석 효율성을 얻은 대신 계층적 문맥을 기억하는 능력을 포기한 가장 가벼운 언어 클래스다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정규 언어 (Type 3) | 문맥 자유 언어 (Type 2) | 선택 기준 |
|:---|:---|:---|:---|
| 인식 기계 모델 | 유한 오토마타 (FA) | 푸시다운 오토마타 (PDA) | 분석 성능 요구 vs 문법 복잡도 |
| 메모리 제어 | 없음 (상태만 존재) | 스택 (LIFO 기억 장치) | 중첩 구조 처리 여부 |
| 컴파일러 적용 | 어휘 분석기 (Scanner/Lex) | 구문 분석기 (Parser/Yacc) | 기호 토큰화 vs 구문 트리(AST) 생성 |

> 요약: 단순 반복 패턴(식별자·숫자)은 정규 언어로, 중첩 구조(괄호·블록)는 문맥 자유 언어로 분리하여 컴파일러 성능을 최적화한다.

**리스크·대응 (기본 불릿):**
- NFA 폭발 리스크: 복잡한 정규 표현식을 DFA로 변환 시 상태 수가 지수적으로 폭발 → 부분집합 구성(Subset Construction) 알고리즘 및 상태 최소화 적용 (지표: DFA 상태 수)
- 백트래킹 지연(ReDoS): 특정 정규 표현식 엔진에서 악의적 입력 시 분석 시간이 $O(2^n)$으로 증가 → 톰슨(Thompson) NFA 시뮬레이션 기반 엔진 사용 (지표: 엣지 케이스 매칭 시간)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 어휘 분석기 자동화: Lex/Flex 도구를 사용하여 정규 표현식 명세로부터 고성능 DFA 기반 Scanner 자동 생성 (성능 지표 확보)
2. 침입 탐지 시스템(IDS) 규칙: Snort/Suricata 등에서 네트워크 패킷 페이로드의 악성 시그니처 패턴을 정규 표현식으로 고속 매칭
3. 데이터 검증 정규화: 이메일, 전화번호 등 사용자 입력 데이터 포맷 검증을 정규 언어 규칙으로 프론트엔드/백엔드 이중 통제

**결론 (2줄):**
- 기술사 판단: 정규 언어는 표현력은 낮지만 O(n)의 고속 판별이 가능하므로, 대용량 로그 검색 및 토큰화의 핵심 엔진으로 채택해야 한다.
- 향후 방향: 보안 영역에서 악의적인 ReDoS(정규표현식 DoS) 공격이 증가하므로, 백트래킹을 방지하는 안전한 정규표현식 엔진 도입이 필수적이다.
