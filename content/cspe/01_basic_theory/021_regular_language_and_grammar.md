# 📖 【암기용】 개념 완전 이해

> 목적: 정규 언어와 정규 문법을 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 유한한 상태 전이로 인식 가능한 문자열 집합
- **왜 필요한가**: 컴파일러 어휘 분석, 로그 패턴 필터링, 입력 검증은 무한한 문자열을 규칙으로 압축해 판정해야 함
- **핵심 직관**: 기억할 정보가 현재 상태 하나면 충분한 언어가 정규 언어임

## 깊이 이해
- **배경·문제의식**: 모든 문자열을 목록으로 저장할 수 없으므로, 문자열 집합을 생성 규칙과 인식 기계로 표현해야 함
- **작동 원리**: 정규 문법은 `A -> aB`, `A -> a`, `A -> ε`처럼 우변에 단말 1개와 비단말 1개 이하만 둔다. 이 규칙은 유한 오토마타의 상태 전이와 1:1 대응함
- **비유**: 지하철 개찰구가 현재 카드 상태만 보고 통과 여부를 결정하듯, 정규 언어도 현재 상태만으로 다음 문자를 처리함
- **구체 예시**: `ab*`는 `a`, `ab`, `abb`를 허용하며 DFA 상태 3개(시작·수락·오류)로 판정 가능함
- **흔한 오해·주의점**: 괄호 중첩 `a^n b^n`은 개수를 기억해야 하므로 정규 언어가 아니며 스택이 필요한 문맥 자유 언어임

## 연결 개념
- 유한 오토마타(DFA/NFA) — 정규 언어의 인식 모델
- 정규 표현식(Regex) — 정규 언어의 실무 표현
- 문맥 자유 문법(CFG) — 중첩 구조를 표현하는 상위 문법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정규 언어는 유한 오토마타로 인식 가능한 문자열 집합이며 정규 문법·정규 표현식과 동치임
> 2. **가치**: 어휘 분석기, 입력 검증, 네트워크 패턴 매칭에서 O(n) 문자 스캔으로 판정 구조를 제공함
> 3. **판단 포인트**: 유한 상태로 충분하면 정규 언어, 중첩 카운트가 필요하면 CFG 이상을 선택함

---

## Ⅰ. 개요 및 필요성

정규 언어는 유한한 상태 전이로 판정 가능한 문자열 집합이다. 컴파일러는 소스코드를 토큰 단위로 나누고, 보안 장비는 패턴 기반 문자열을 선형 스캔으로 판정한다. 정규 언어는 구현 비용과 판정 복잡도를 낮추는 기초 모델임

---

## Ⅱ. 구조 및 구성요소

```text
정규 표현식 -> NFA -> DFA -> 최소 DFA
정규 문법 -> NFA/DFA
입력 문자열 -> 상태 전이표 -> 수락/거부
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규 문법 | 문자열 생성 규칙 제공 | 우선형/좌선형, `A -> aB` 형태 |
| 정규 표현식 | 패턴을 간결하게 표현 | 합집합·연접·클린 스타 |
| 유한 오토마타 | 문자열 수락 여부 판정 | DFA/NFA 동치, O(n) 판정 |
| 최소 DFA | 중복 상태 제거 | 상태 수 감소, 전이표 단순화 |

> 요약: 정규 언어는 표현식·문법·오토마타가 서로 변환 가능한 동일 표현 체계임

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 문자열 -> 현재 상태 확인 -> 전이 함수 적용 -> 다음 상태
반복 처리 -> 입력 종료 -> 수락 상태 여부 판정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 알파벳과 패턴 규칙 식별 | Σ, 시작 상태, 수락 상태 명시 |
| 2 | 정규식 또는 문법을 NFA/DFA로 변환 | ε-전이 제거, 전이 누락 점검 |
| 3 | 입력 문자별 상태 전이 수행 | 문자 1개당 전이 1회 |
| 4 | 입력 종료 후 수락 상태 확인 | 최종 상태 ∈ F이면 수락 |

> 요약: 정규 언어 판정은 문자 길이 n에 대해 상태 전이 n회로 완료되는 선형 처리임

---

## Ⅳ. 특징

| 구분 | 정규 언어 | 문맥 자유 언어 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 기억 구조 | 현재 상태 1개 | 스택 필요 | DFA 상태 수 k, 스택 0개 |
| 표현 대상 | 토큰·패턴 | 괄호·블록 중첩 | `ab*` 가능, `a^n b^n` 불가 |
| 판정 비용 | O(n) | 일반 CFG CYK O(n^3) | 실시간 필터링은 정규 언어 우선 |
| 실무 도구 | Regex, Lex | Parser Generator | 어휘 분석과 구문 분석 분리 |

> 요약: 정규 언어는 중첩 구조를 포기하는 대신 O(n) 판정과 작은 상태 전이표를 확보함

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 표현력 | CFG·PDA | DFA·NFA·정규식 | 중첩 구조 없고 현재 상태만 필요할 때 |
| 비용/성능 | 백트래킹 Regex | DFA 전이표 | 입력 길이 n 기준 O(n) 보장 필요 |
| 운영/위험 | 임의 패턴 허용 | 제한된 정규 패턴 | ReDoS, 상태 폭증, 길이 제한 점검 |

> 요약: 정규 언어는 표현력보다 O(n) 판정과 구현 단순성이 중요한 패턴 처리에 선택함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| ReDoS | 백트래킹 정규식의 지수 탐색 | DFA 엔진, 타임아웃 100ms, 입력 길이 제한 | 패턴별 최악 지연 p99 |
| 상태 폭증 | NFA를 DFA로 변환할 때 부분집합 증가 | 상태 수 상한, 최소화, 패턴 분할 | DFA 상태 수 k |
| 표현 한계 | 괄호 중첩·재귀 구조 요구 | CFG 파서로 분리 | 중첩 깊이 요구 여부 |

> 요약: 정규 언어 적용 리스크는 ReDoS와 상태 폭증이며, DFA 상태 수와 p99 지연으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 판정 시간 | 입력 n 문자 기준 O(n), p99 100ms 이하 | 패턴 벤치마크 |
| 상태 규모 | DFA 상태 수 k 상한 준수 | 전이표 크기 검토 |
| 정확도 | 허용/거부 테스트 100% 통과 | 양성·음성 케이스 테스트 |

> 요약: 정규 언어 도입 효과는 O(n) 판정, 상태 수, 테스트 통과율로 판단함

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 어휘 분석: 식별자 `[A-Za-z_][A-Za-z0-9_]*`, 숫자 `[0-9]+`를 DFA 전이표로 생성
2. 보안 로그 필터링: IP·URL·토큰 패턴을 정규식으로 분류하고 ReDoS 방지를 위해 백트래킹 Regex 대신 DFA 엔진 적용
3. 프로토콜 입력 검증: 허용 문자 집합·길이 1~255·상태 전이를 명시해 비정상 입력을 수신 단계에서 차단

**결론 (2줄):**
- 기술사 판단: 토큰·패턴 판정은 정규 언어, 괄호 중첩·재귀 구조는 CFG로 분리 설계함
- 향후 방향: Regex 기반 검증은 DFA 컴파일, 타임아웃, 길이 제한을 함께 적용해 O(n) 처리 경로를 보장해야 함
