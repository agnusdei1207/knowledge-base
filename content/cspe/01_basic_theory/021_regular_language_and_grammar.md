# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 정규 언어(Regular Language)는 **촘스키 위계** Type 3에 해당하는 가장 단순한 **형식 언어** 클래스로, **정규 표현식**으로 서술되고 **유한 오토마타(FA, 020 참조)**로 인식 가능한 문자열 집합이다.
- **왜 필요한가**: 컴파일러 어휘 분석(Lexer)에서 소스 코드를 토큰으로 분리하거나, 정규표현식으로 대용량 로그를 패턴 매칭할 때 O(N) 선형 시간 판별이 가능한 가장 가벼운 언어 모델이 필요하다.
- **핵심 직관**: "기억력이 없는 기계(상태만 존재)가 인식할 수 있는 패턴의 범위" — 정규 언어는 유한 오토마타가 스택·테이프 없이 상태 전이만으로 판별 가능한 문자열의 전체 집합이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

정규 언어의 세 가지 등가 표현(정규 표현식·정규 문법·유한 오토마타)과 촘스키 위계에서의 위치를 먼저 세운다. FA의 상세(DFA·NFA·5튜플)는 020 참조.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 촘스키 위계 (상위 키워드) | 형식 언어를 문법 제약 강도별로 Type 0~3으로 분류하는 계층 체계 | 언어의 난이도 등급표 |
| Type 3 (정규 언어) | 가장 제약이 강하고 단순한 언어 — FA로 인식 | 변수명·숫자·키워드 패턴 |
| 정규 표현식 (Regex) | 연결·합집합·클레이니 스타 3연산으로 정규 언어를 서술하는 대수식 | `[A-Z]+[0-9]*` |
| 정규 문법 (Regular Grammar) | 좌변이 단일 비단말, 우변이 단말+비단말(또는 단말만)인 선형 생성 규칙 | A → aB 또는 A → a (우선형 기준) |
| 유한 오토마타 (FA) | 정규 언어를 인식하는 추상 기계 (020 참조) | 기억 없이 상태만 전이하는 자판기 |
| 클레이니 정리 | 정규 표현식·NFA·DFA가 인식하는 언어 집합이 동일함을 증명 | 세 표현이 같은 집합을 가리킴 |
| 클레이니 스타 (*) | 0번 이상 반복을 뜻하는 정규 표현식 연산자 | a* = {ε, a, aa, aaa, …} |
| 닫힘 성질 (Closure) | 정규 언어 간 합집합·교집합·여집합·연결·스타 연산 결과도 정규 언어 | 정규 패턴끼리 조합해도 정규 |

## 깊이 이해
- **배경·문제의식**: 프로그래밍 언어의 텍스트를 기계가 처리하려면, 복잡한 문맥을 이해하는 비싼 모델이 아니라, 변수명·숫자·키워드처럼 단순하고 규칙적인 패턴을 가장 가벼운 비용으로 분리하는 모델이 먼저 필요하다.
- **작동 원리 — 3자 등가성**:
  - **정규 표현식 → NFA (Thompson 구성)**: 정규 표현식의 각 연산(연결·합집합·클레이니 스타)을 NFA 조각으로 조립한다. 사람이 패턴을 작성하는 수단이다.
  - **NFA → DFA (부분집합 구성법, 020 참조)**: NFA의 비결정성을 제거해 매 입력마다 다음 상태가 1개로 확정되는 DFA를 생성한다.
  - **DFA → 정규 표현식 (상태 제거법)**: DFA에서 상태를 하나씩 제거하며 전이를 정규 표현식으로 합산해 원래 언어를 표현한다.
  - 이 순환 변환이 가능하므로 세 표현은 동일한 언어 집합(정규 언어)을 정의한다 — 이것이 클레이니 정리이다.
  - **정규 문법과의 등가**: 정규 문법 A → aB는 "상태 A에서 입력 a를 읽고 상태 B로 이동"과 1:1 대응하므로 FA와 직접 변환 가능하다.
- **비유**: 정규 표현식은 "목적지 이름"(패턴 서술), 정규 문법은 "조립 설명서"(생성 규칙), 유한 오토마타는 "자동 판별기"(인식 기계) — 같은 대상(정규 언어)을 서술·생성·인식하는 세 관점이다.
- **구체 예시**:
  - 정규 표현식: `a(a|b)*abb` — "a로 시작하고 abb로 끝나는 a·b 문자열"
  - 정규 문법(우선형): S → aA, A → aA | bA | aB, B → bC, C → b
  - 이 세 표현은 동일한 문자열 집합을 정의하며, DFA로 변환 시 O(N) 매칭이 가능하다.
- **흔한 오해·주의점**:
  - **"정규 표현식은 모든 패턴을 표현할 수 있다"**: 정규 언어는 괄호 짝 맞추기(a^n b^n), HTML 태그 중첩 같은 재귀 구조를 표현할 수 없다. 이런 계층적 구조는 문맥 자유 문법(Type 2, 022 참조)의 영역이다.
  - **실무 정규표현식 ≠ 이론적 정규 표현식**: Perl·Python의 정규표현식은 역참조(backreference), 전방탐색 등 정규 언어를 초과하는 기능을 포함하며, 이로 인해 O(2^N) 백트래킹(ReDoS)이 발생할 수 있다.
  - **펌핑 보조정리**: 특정 언어가 정규 언어가 아님을 증명하는 도구로, "충분히 긴 문자열의 일부를 반복해도 여전히 언어에 속하는가?"를 검사한다.

## 연결 개념
- **오토마타 이론 (020)**: 정규 언어를 인식하는 DFA·NFA의 구조와 변환 메커니즘을 다룸.
- **문맥 자유 문법 (022)**: 스택을 활용해 정규 언어가 표현 불가능한 재귀·중첩 구조를 처리하는 상위 언어 클래스.
- **컴파일러 구조 (073)**: 어휘 분석기(Lexer)가 정규 표현식·DFA로 토큰을 생성하는 실무 파이프라인.
- **형식 언어 이론 (072)**: 촘스키 위계 전체(Type 0~3)를 아우르는 상위 이론 체계.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정규 언어는 촘스키 Type 3으로 정규 표현식·정규 문법·유한 오토마타 3자가 등가인 가장 단순한 형식 언어 클래스임.
> 2. **가치**: 스택 없이 유한 상태 전이만으로 O(N) 선형 판별이 가능해 컴파일러 어휘 분석·보안 패턴 매칭의 핵심 엔진으로 활용됨.
> 3. **판단 포인트**: 재귀·중첩 구조(a^n b^n)는 정규 언어로 표현 불가하므로 어휘 분석(정규)과 구문 분석(문맥 자유, 022)을 분리 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 언어의 이론적 정의와 3자 등가성 | 촘스키 Type 3, 정규 표현식·정규 문법·FA의 등가(클레이니 정리) | 정규 언어와 문맥 자유 언어 혼동 |
| 정규 문법 생성 규칙 제약 | A → aB 또는 A → a (우선형) — 좌변 단일 비단말, 우변 선형 | 비선형 규칙(A → aBb)을 정규 문법으로 오기 |
| 실무 응용 연결 | 컴파일러 Lexer, 정규표현식 엔진, 보안 패턴 매칭 | 추상 이론만 나열하고 실무 응용 누락 |

> 요약: 정규 표현식·정규 문법·FA의 3자 등가성을 클레이니 정리로 근거하고, 어휘 분석 파이프라인에서의 역할과 한계(재귀 구조 불가)를 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 촘스키 위계 Type 3에 해당하며 유한 오토마타로 인식 가능한 가장 단순한 형식 언어 클래스임
- 배경: 프로그래밍 언어의 토큰(변수명·숫자·키워드) 식별에 문맥 이해가 불필요한 가벼운 수학 모델이 필요함
- 필요성: O(N) 선형 시간 패턴 판별로 컴파일러 어휘 분석과 대용량 로그 검색 성능을 보장함

## Ⅱ. 구조 및 구성요소
선형 구조도 (3자 등가 관계):

    정규 표현식(패턴 서술) <-> 정규 문법(생성 규칙) <-> 유한 오토마타(인식 기계)
                                     |
                                     +-> 어휘 분석기(Lex/Flex) -> 토큰 스트림

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규 표현식 | 연결·합집합·클레이니 스타 3연산으로 패턴을 대수적 서술 | 사람이 패턴을 작성하는 수단 |
| 정규 문법 | A → aB 또는 A → a 형태의 선형 생성 규칙으로 언어 정의 | 우선형/좌선형 존재, FA 전이와 1:1 대응 |
| 유한 오토마타 (FA) | 상태 전이로 문자열 수락/거절 판별 (020 참조) | DFA: O(N) 보장, NFA: 설계 편의 |

> 요약: 정규 표현식·정규 문법·FA 3자는 클레이니 정리에 의해 동일한 언어 집합(정규 언어)을 서술·생성·인식하는 등가 표현임.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (어휘 분석기의 정규 언어 인식):

    소스 코드 입력 -> 문자 스트림 -> 정규표현식→NFA(Thompson) -> NFA→DFA(부분집합 구성) -> DFA 상태 전이 매칭 -> 토큰 출력

1. 패턴 컴파일: 정규 표현식을 Thompson 구성으로 NFA로 변환한 뒤 부분집합 구성법으로 DFA를 생성함
2. 문자 스캔: 입력 문자열의 각 기호를 DFA 전이 함수에 대입해 상태를 순차 이동함
3. 수용 판별: 문자열 종료 시 현재 상태가 수용 상태(F)에 속하면 패턴 일치(Accept)를 반환함
4. 토큰 출력: 매칭된 문자열을 해당 토큰 유형(Identifier·Number·Keyword)으로 분류해 구문 분석기에 전달함

> 요약: 정규 표현식을 DFA로 컴파일한 뒤 입력을 O(N) 한 번의 스캔으로 토큰화하는 파이프라인임.

## Ⅳ. 특징
- O(N) 선형 판별: DFA로 변환 시 백트래킹·스택 없이 입력 길이에 비례하는 단일 스캔으로 판별 완료함
- 메모리 부재 한계: 유한 오토마타는 과거 입력 횟수를 기억할 수 없어 a^n b^n 같은 재귀·중첩 구조 인식 불가 — 푸시다운 오토마타(PDA, 022)가 필요함
- 닫힘 성질: 합집합·교집합·여집합·연결·클레이니 스타 연산에 대해 닫혀 있어 복합 패턴을 정규 언어 내에서 자유롭게 조합 가능함
- 판별 한계 증명: 펌핑 보조정리로 특정 언어가 정규 언어가 아님을 반증법으로 증명 가능함

## Ⅴ. 심화 비교 및 적용 판단

정규 언어가 촘스키 위계에서 차지하는 위치를 문맥 자유 언어(022)와 대조함. FA 내부(DFA vs NFA)의 비교는 020 참조.

| 구분 | 정규 언어 (Type 3) | 문맥 자유 언어 (Type 2) | 선택 기준 |
|:---|:---|:---|:---|
| 인식 기계 | 유한 오토마타 (FA) | 푸시다운 오토마타 (PDA) | 스택 없이 처리 가능 여부 |
| 메모리 | 없음 (상태만 존재) | 스택 (LIFO) | 중첩 구조 처리 필요 여부 |
| 표현 한계 | a^n b^n 불가, 재귀 불가 | 재귀·중첩 표현 가능 | 괄호·블록 중첩 유무 |
| 컴파일러 적용 | 어휘 분석기 (Lexer) | 구문 분석기 (Parser) | 토큰화 vs AST 생성 |
| 시간 복잡도 | O(N) 보장 (DFA) | O(N)~O(N³) (파서 종류 의존) | 실시간 대량 매칭 요구 |

> 요약: 단순 반복 패턴(변수명·숫자)은 정규 언어(Type 3)로 O(N) 처리하고, 중첩 구조(괄호·블록)는 문맥 자유 언어(Type 2)로 분리해 컴파일러 성능을 최적화함.

**리스크·대응:**
- NFA→DFA 상태 폭발: 복잡한 정규 표현식의 DFA 변환 시 상태 수가 2^|Q|으로 증가 → Hopcroft 알고리즘으로 최소 DFA 축소 (지표: 최소화 후 상태 수)
- ReDoS 공격: 백트래킹 NFA 엔진(PCRE 등)에 악의적 입력 시 O(2^N) 지연 → DFA 기반 엔진(Google RE2)으로 교체해 선형 시간 보장 (지표: 에지 케이스 매칭 시간)

**점검 지표:**
- 토큰화 처리량: GB 단위 로그 파일의 패턴 스캔 시 O(N) 선형 종료 여부 — 초당 처리 바이트수 측정
- 패턴 컴파일 크기: 정규표현식→DFA 변환 시 상태 테이블이 가용 메모리 내 적재 가능한지 프로파일링

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 컴파일러 어휘 분석기: Lex/Flex에 정규 표현식 명세를 입력해 DFA 기반 Scanner를 자동 생성하고 소스 코드를 O(N)에 토큰화함
2. 보안 패턴 매칭: IDS/WAF(Snort·Suricata)에서 공격 시그니처를 정규 표현식으로 정의하고 통합 DFA로 합쳐 패킷 페이로드를 실시간 필터링함
3. 데이터 검증: 이메일·전화번호·우편번호 등 입력 형식을 정규 표현식으로 정의해 프론트엔드·백엔드 이중 검증을 수행함

**결론:**
- 기술사 판단: 정규 언어는 표현력은 낮지만 O(N) 고속 판별이 가능하므로, 대용량 로그 검색·토큰화 엔진의 핵심 기반으로 채택하되 재귀 구조는 CFG(022)로 분리 설계해야 함
- 향후 방향: ReDoS 공격 증가로 백트래킹 방지 엔진(RE2) 도입이 확대되며, 하드웨어 가속(FPGA DFA)으로 네트워크 패턴 매칭 처리량을 높이는 방향으로 발전하고 있음
