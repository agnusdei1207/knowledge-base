## Ⅰ. 개요
- **정의**: DFA/NFA로 인식 가능한 문자열 집합과 이를 생성하는 문법 체계
- **배경/필요성**: 문자열 패턴 매칭, 어휘 분석 등에서 계산 가능 여부를 판별할 수학적 기반이 필요함
- **비유**: 회전문(턴스타일)처럼 상태만 기억하고, 들어온 입력에 따라 통과/거부를 결정하는 장치

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 언어의 3자 등가성 이해 | 정규 표현식 = 정규 문법 = 유한 오토마타 | 등가성 증명 방향(변환 경로)을 혼동하지 않을 것 |
| 한계 인식 능력 | 펌핑 레마로 비정규 언어 판별 | 펌핑 레마는 충분조건이 아닌 필요조건임을 명시 |
| 촘스키 계층 내 위치 | Type-3 문법에 해당 | 문맥 자유 문법(022 참조)과의 포함 관계 구분 |

> 요약: 유한 상태만으로 인식 가능한 언어 클래스이며, 세 가지 표현이 동치임

## Ⅱ. 구성요소
```text
  정규 표현식 (RE)
        |
        v
  +-----+------+
  | NFA 변환   |--- Thompson 구성법
  +-----+------+
        |
        v
  +-----+------+
  | DFA 변환   |--- 부분집합 구성법
  +-----+------+
        |
        v
  +-----+------+
  | 정규 문법   |--- 우선형/좌선형 생성 규칙
  +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정규 표현식(RE) | 합집합·접합·클리니 폐포 연산으로 패턴을 기술하는 표기법 | 검색창의 와일드카드 패턴 |
| 유한 오토마타(FA) | 유한 개의 상태와 전이 함수로 문자열을 수락/거부하는 기계(020 참조) | 신호등 — 상태 전환만 존재 |
| 정규 문법 | `A -> aB` 또는 `A -> a` 형태의 생성 규칙으로 언어를 정의하는 문법 | 한 글자씩 앞으로만 읽는 레시피 |
| 펌핑 레마 | 충분히 긴 정규 언어 문자열은 반복 가능한 부분이 존재함을 보장하는 정리 | 순환 도로 — 한 바퀴 더 돌아도 같은 길 |

> 요약: RE·FA·정규 문법이 동일한 언어 클래스를 정의하며, 펌핑 레마가 한계를 규정함

## Ⅲ. 절차
```text
  패턴 정의(RE) --> NFA 구성 --> DFA 변환 --> DFA 최소화
```
- 1단계: 인식할 패턴을 정규 표현식으로 기술함
- 2단계: Thompson 구성법으로 RE를 epsilon-NFA로 변환함
- 3단계: 부분집합 구성법(Subset Construction)으로 NFA를 DFA로 변환함
- 4단계: 등가 상태 병합(Hopcroft 알고리즘)으로 DFA 상태 수를 최소화함

> 요약: RE에서 출발하여 NFA → DFA → 최소 DFA 순으로 변환하여 인식기를 완성함

## Ⅳ. 문제점
- 표현력 한계: 유한 상태만 사용 — 괄호 짝 맞추기(`a^n b^n`) 등 무한 기억이 필요한 언어를 표현 불가
- 상태 폭발: 부분집합 구성 시 NFA 상태 `n`개가 DFA 상태 최대 `2^n`개로 확장됨
- 모호한 패턴 설계: 복잡한 RE 작성 시 의도하지 않은 문자열까지 수락하는 과잉 매칭 발생

> 요약: 유한 메모리 제약, 상태 폭발, 과잉 매칭이 실무 적용의 주요 장벽임

## Ⅴ. 개선방안
1. 단기: 표현력이 부족한 경우 문맥 자유 문법(022 참조)·PDA로 상위 언어 클래스 활용
2. 중기: 지연 평가(Lazy DFA) 기법으로 필요한 상태만 점진적으로 생성하여 상태 폭발 완화
3. 장기: 정적 분석 도구를 통해 RE 작성 시 과잉 매칭 여부를 자동 검증하는 체계 구축

> 요약: 상위 문법 활용, 지연 상태 생성, 자동 검증으로 각 문제를 대응함

## Ⅵ. 전망
- 발전 방향: 대규모 로그 필터링·네트워크 패킷 검사 등에서 하드웨어 가속 정규 표현식 엔진 확산
- 기술사적 판단: 정규 언어는 계산 이론의 기초이며, 어휘 분석·프로토콜 검증 등 실무 전 영역에 적용됨
- 기술사 제언: 촘스키 계층 전체를 조망하여 문제 복잡도에 맞는 언어 클래스를 선택하는 설계 역량 필요
