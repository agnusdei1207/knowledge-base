# 📖 【암기용】 개념 완전 이해

> 목적: 정규 언어와 정규 문법을 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 정규 언어와 정규 문법은 **표현 방식은 다르지만 인식 능력이 완전히 동일한 세 가지 형식(정규 표현식·정규 문법·유한 오토마타)의 동치 삼각형**이다 — 이 동치성 덕분에 사람은 정규식으로 편하게 패턴을 쓰고, 컴파일러는 이를 DFA로 바꿔 초고속으로 실행한다.
- **왜 필요한가**: 어휘 분석기·보안 필터처럼 실시간으로 대량의 문자열을 판정해야 하는 시스템은, 사람이 쓰기 쉬운 표현(정규식)과 기계가 실행하기 빠른 표현(DFA)이 다르다. 이 둘을 자동으로 오가는 변환 파이프라인이 실무의 핵심이다.
- **핵심 직관**: 정규식은 레시피, 정규 문법은 레시피를 만드는 문법 규칙, DFA는 그 레시피를 실행하는 기계다 — 셋 다 같은 언어(요리)를 만든다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 동치성 (Equivalence) | 서로 다른 형식이 정확히 같은 언어 집합을 표현할 때 쓰는 용어 — 정규식과 정규 문법과 유한 오토마타가 동치 | 같은 곡을 악보로도, 가사로도, 연주로도 표현 가능 |
| 톰슨 구성법 (Thompson's Construction) | 정규 표현식을 NFA로 기계적으로 변환하는 알고리즘 | 레시피를 요리 순서도로 자동 변환 |
| 부분집합 구성법 (Subset Construction) | NFA를 DFA로 변환하는 알고리즘(020 참조) | 여러 분신 상태 조합에 이름표를 붙여 단일 지도로 재작성 |
| 최소 DFA (Minimal DFA) | 동일 언어를 인식하는 DFA 중 상태 수가 가장 적은 형태 | 같은 지도에서 겹치는 정거장을 합쳐 가장 단순하게 그린 것 |
| 마이힐-네로드 정리 (Myhill-Nerode Theorem) | 두 상태가 이후 어떤 입력에도 항상 같은 결과를 내면 하나로 합칠 수 있다는 최소화의 이론적 근거 | 앞으로의 반응이 똑같은 정거장은 같은 정거장으로 취급 |
| 홉크로프트 알고리즘 (Hopcroft's Algorithm) | DFA를 빠르게(N log N 수준으로) 최소화하는 실무 표준 알고리즘 | 최소 지도를 빠르게 계산하는 공식 절차 |
| 폐쇄 성질 (Closure Property) | 정규 언어끼리 특정 연산(합집합·교집합·여집합·연접·반복)을 해도 결과가 여전히 정규 언어로 남는 성질 | 두 정규 재료를 섞어도 여전히 정규 요리가 나옴 |

## 깊이 이해

### 동치 삼각형이 실제로 어떻게 오가는가 — 컴파일러 파이프라인 예시
- 정규식 "a 다음에 b 또는 c가 0번 이상 반복"을 예로 든다.
- 1단계(톰슨 구성법): 정규식의 각 연산자(연접·합집합·반복)를 ε-전이가 포함된 NFA 조각으로 바꾸고 이어붙인다. 연산자 몇 개짜리 정규식이면 NFA 상태도 그만큼만 만들어진다.
- 2단계(부분집합 구성법): NFA에서 "동시에 활성화 가능한 상태 집합"들을 묶어 DFA 상태로 만든다. 위 예시는 상태가 3개 정도(시작, a 읽은 후, b·c 반복 상태)로 수렴한다.
- 3단계(최소화, 홉크로프트 알고리즘): 마이힐-네로드 정리에 따라 "이후 반응이 완전히 같은 상태"를 하나로 합친다. 상태가 우연히 여러 개로 만들어졌어도 실제로 구별되는 상태만 남기고 나머지를 제거해 최소 DFA로 압축한다.
- 이 3단계가 Lex·Flex 같은 어휘 분석기 생성 도구가 내부적으로 실제 수행하는 절차다.

### 폐쇄 성질 — 왜 정규 언어는 조합해도 안전한가
- 정규 언어 두 개를 합집합·연접·반복(클린 스타)·교집합·여집합으로 조합해도 결과는 항상 다시 정규 언어다.
- 실무 의미: 여러 개의 개별 패턴(IP 형식, 이메일 형식, 날짜 형식)을 정규식으로 각각 만든 뒤 합집합으로 이어 붙여도, 결과는 여전히 정규 언어이므로 하나의 DFA로 병합해 O(N) 판정을 유지할 수 있다. 이것이 Aho-Corasick 같은 다중 패턴 매칭 알고리즘이 수천 개의 시그니처를 단일 DFA로 동시에 매칭할 수 있는 이론적 근거다.

### 최소화가 실무에 주는 이득 — 수치로 확인
- NFA를 DFA로 변환하면 최악의 경우 상태 수가 2의 n제곱(멱집합)까지 늘어날 수 있다. NFA 상태가 10개면 이론상 DFA 상태가 최대 1,024개까지 가능하다.
- 홉크로프트 최소화는 이렇게 늘어난 DFA에서 행동이 똑같은 상태를 합쳐 실제로 필요한 최소 상태 수(예: 실제로는 20~30개)로 줄인다. 상태 수가 줄면 전이 테이블 크기(상태 수 × 알파벳 크기)가 줄어 메모리 사용량과 캐시 적중률이 개선된다.

### 정규식 엔진의 두 갈래 — 왜 실무에서 성능 사고가 나는가
- DFA 기반 엔진(RE2, Aho-Corasick): 미리 정규식을 DFA로 컴파일해두므로 입력 길이 N에 대해 항상 O(N) 시간이 보장된다. 대신 백레퍼런스 같은 정규 언어 범위를 벗어난 기능은 지원하지 못한다.
- 백트래킹 기반 엔진(PCRE, 대부분 언어의 기본 정규식): 정규 언어보다 강력한 기능(백레퍼런스, 전방탐색)을 지원하지만, 내부적으로 NFA를 재귀 백트래킹으로 시뮬레이션한다. 중첩된 반복자(예: 반복 안에 또 반복)에 실패하는 입력을 주면 탐색 경로가 지수적으로 폭발하는 ReDoS(Regular Expression Denial of Service)가 발생할 수 있다.
- 판별 기준: O(N) 시간 보장이 필요한 실시간 보안 필터·게이트웨이는 DFA 엔진을, 백레퍼런스 등 표현력이 필요한 검증 로직은 타임아웃을 반드시 걸고 백트래킹 엔진을 쓴다.

### 비유
- 정규식·정규 문법·유한 오토마타는 같은 노래를 표현하는 악보·가사지·실제 연주와 같다 — 형식은 다르지만 결과물(인식되는 언어)은 완전히 동일하다.

## 연결 개념
- 유한 오토마타(DFA·NFA) — 동치 삼각형의 한 축이자 실행 엔진 (020 참조)
- 정규 언어 — 이 삼각형이 표현하는 대상 언어 계층과 그 한계(펌핑 정리) (021_regular_language 참조)
- 문맥 자유 문법 — 정규 언어로 못 푸는 중첩 구조를 해결하는 상위 계층 (022 참조)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정규 언어는 유한 오토마타로 인식 가능한 문자열 집합이며 정규 문법·정규 표현식과 동치임
> 2. **가치**: 어휘 분석기, 입력 검증, 네트워크 패턴 매칭에서 O(n) 문자 스캔으로 판정 구조를 제공함
> 3. **판단 포인트**: 유한 상태로 충분하면 정규 언어, 중첩 카운트가 필요하면 CFG 이상을 선택함

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 언어 계층 이해 확인 | 정규 언어 = FA·정규문법·정규표현식 동치, 촘스키 위계 내 위치 | 정규 표현식(도구)과 정규 언어(이론) 혼동 |
| 표현 한계 판단 확인 | 펌핑 정리로 a^n b^n 인식 불가 증명 | 중첩 구조 반례 없이 "정규식으로 충분" 단정 |
| 실무 매핑 역량 확인 | 어휘 분석기·입력 검증·패턴 매칭의 O(n) 판정 | 이론만 쓰고 컴파일러·보안 필터 적용처 누락 |

> 요약: 이 문제는 정의 암기가 아니라 유한 상태 표현의 한계 증명과 CFG 전환 기준을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 정규 언어는 유한한 상태 전이로 판정 가능한 문자열 집합이다
- 배경: 컴파일러는 소스코드를 토큰 단위로 나누고, 보안 장비는 패턴 기반 문자열을 선형 스캔으로 판정한다
- 필요성: 정규 언어는 구현 비용과 판정 복잡도를 낮추는 기초 모델임

---

## Ⅱ. 구조 및 구성요소

```text
정규 표현식 -> NFA -> DFA -> 최소 DFA
정규 문법 -> NFA/DFA
입력 문자열 -> 상태 전이표 -> 수락/거부
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규 문법 | 문자열 생성 규칙 제공 | 우선형/좌선형, `A -> aB` 형태 |
| 정규 표현식 | 패턴을 간결하게 표현 | 합집합·연접·클린 스타 |
| 유한 오토마타 | 문자열 수락 여부 판정 | DFA/NFA 동치, O(n) 판정 |
| 최소 DFA | 중복 상태 제거 | 상태 수 감소, 전이표 단순화 |

> 요약: 정규 언어는 표현식·문법·오토마타가 서로 변환 가능한 동일 표현 체계임

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 문자열 -> 현재 상태 확인 -> 전이 함수 적용 -> 다음 상태
반복 처리 -> 입력 종료 -> 수락 상태 여부 판정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 알파벳과 패턴 규칙 식별 | Σ, 시작 상태, 수락 상태 명시 |
| 2 | 정규식 또는 문법을 NFA/DFA로 변환 | ε-전이 제거, 전이 누락 점검 |
| 3 | 입력 문자별 상태 전이 수행 | 문자 1개당 전이 1회 |
| 4 | 입력 종료 후 수락 상태 확인 | 최종 상태 ∈ F이면 수락 |

> 요약: 정규 언어 판정은 문자 길이 n에 대해 상태 전이 n회로 완료되는 선형 처리임

## Ⅳ. 특징

| 구분 | 정규 언어 | 문맥 자유 언어 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 기억 구조 | 현재 상태 1개 | 스택 필요 | DFA 상태 수 k, 스택 0개 |
| 표현 대상 | 토큰·패턴 | 괄호·블록 중첩 | `ab*` 가능, `a^n b^n` 불가 |
| 판정 비용 | O(n) | 일반 CFG CYK $O(n^3)$ | 실시간 필터링은 정규 언어 우선 |
| 실무 도구 | Regex, Lex | Parser Generator | 어휘 분석과 구문 분석 분리 |

> 요약: 정규 언어는 중첩 구조를 포기하는 대신 O(n) 판정과 작은 상태 전이표를 확보함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 엔진 구현 방식 | 확장 정규식(PCRE: lookahead·backreference 지원) | 순수 정규 언어(Type-3) 기반 DFA 엔진 | 이론적 O(n) 보장 필요 시 확장 기능 배제 |
| 비용/성능 | 백트래킹 Regex | DFA 전이표 | 입력 길이 n 기준 O(n) 보장 필요 |
| 운영/위험 | 임의 패턴 허용 | 제한된 정규 패턴 | ReDoS, 상태 폭증, 길이 제한 점검 |

> 요약: 실무 정규식 엔진은 백레퍼런스 등으로 이론적 정규 언어보다 강력하지만, O(n) 보장이 필요한 구간은 순수 DFA 엔진으로 분리함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| ReDoS | 백트래킹 정규식의 지수 탐색 | DFA 엔진, 타임아웃 100ms, 입력 길이 제한 | 패턴별 최악 지연 p99 |
| 상태 폭증 | NFA를 DFA로 변환할 때 부분집합 증가 | 상태 수 상한, 최소화, 패턴 분할 | DFA 상태 수 k |
| 표현 한계 | 괄호 중첩·재귀 구조 요구 | CFG 파서로 분리 | 중첩 깊이 요구 여부 |

> 요약: 정규 언어 적용 리스크는 ReDoS와 상태 폭증이며, DFA 상태 수와 p99 지연으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 판정 시간 | 입력 n 문자 기준 O(n), p99 100ms 이하 | 패턴 벤치마크 |
| 상태 규모 | DFA 상태 수 k 상한 준수 | 전이표 크기 검토 |
| 정확도 | 허용/거부 테스트 100% 통과 | 양성·음성 케이스 테스트 |

> 요약: 정규 언어 도입 효과는 O(n) 판정, 상태 수, 테스트 통과율로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 어휘 분석: 식별자 `[A-Za-z_][A-Za-z0-9_]*`, 숫자 `[0-9]+`를 DFA 전이표로 생성
2. 보안 로그 필터링: IP·URL·토큰 패턴을 정규식으로 분류하고 ReDoS 방지를 위해 백트래킹 Regex 대신 DFA 엔진 적용
3. 프로토콜 입력 검증: 허용 문자 집합·길이 1~255·상태 전이를 명시해 비정상 입력을 수신 단계에서 차단

**결론 (2줄):**
- 기술사 판단: 토큰·패턴 판정은 정규 언어, 괄호 중첩·재귀 구조는 CFG로 분리 설계함
- 향후 방향: Regex 기반 검증은 DFA 컴파일, 타임아웃, 길이 제한을 함께 적용해 O(n) 처리 경로를 보장해야 함
