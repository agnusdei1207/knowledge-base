## 미리 알고가기

- 병렬 알고리즘: 독립 작업을 여러 처리 장치에서 동시에 수행하도록 설계한 알고리즘임
- 병렬 공유 메모리 모델(PRAM): 동기식 공유 메모리와 다수 프로세서를 가정한 계산 모델임
- 총 연산량(Work): 모든 프로세서가 수행한 연산 수의 합임
- 최장 의존 시간(Span): 의존성 때문에 병렬화해도 줄지 않는 최장 경로 시간임
- 동시 접근 유형(EREW·CREW·ERCW·CRCW): 공유 메모리의 동시 읽기·쓰기 허용 범위로 나눈 네 가지 유형임
- 동시 쓰기 규칙(CRCW 충돌 규칙): 우선순위·동일값·임의 선택 중 하나로 반영할 값을 정함
- 리덕션 트리: 여러 부분 결과를 트리 형태로 병합해 하나의 결과를 만드는 병렬 구조임
- 워크 스틸링: 유휴 실행 단위가 다른 실행 단위의 대기 작업을 가져오는 동적 분배 방식임

## 쉽게 이해하기
- 여러 일꾼이 하나의 칠판(공유 메모리)을 보며 정해진 박자에 맞춰 동시에 읽고 쓰는 상황과 같음
- 일꾼을 아무리 늘려도 줄지 않는 최소 대기 줄(Span)이 있어 이것이 병렬 처리의 실제 한계를 정함

## 작성 근거(검토용)

- 개요는 병렬 알고리즘과 PRAM을 함께 정의해 설계 대상과 분석 모델을 연결함
- 특징은 이상 모델, Work/Span, 접근 충돌, 실제 하드웨어 제약을 병렬 판단 기준으로 선정함
- Ⅲ은 동시 읽기·쓰기 허용 여부를 중심으로 PRAM 네 변종의 본질을 비교함
- Ⅴ는 스텝별 동시 읽기·연산·쓰기와 동기화 배리어로 PRAM 변종별 충돌 처리 절차를 드러냄
- 구조 도식은 리덕션의 단계별 병합 구조를 보여줌
- 부하 불균형과 공유 메모리 동기화는 병렬 성능을 제한하는 주요 조건임

## Ⅰ. 개요

- **정의/개념**: 병렬 알고리즘은 작업을 동시 실행 단위로 나누며, PRAM은 공유 메모리 병렬 계산의 이론적 한계를 분석하는 모델임
- **배경/필요성**: 대규모 연산의 처리 시간을 줄이기 위해 병렬성·동기화·메모리 접근 비용의 설계 기준이 필요함

## Ⅱ. 특징

- PRAM은 공유 메모리 접근을 단위 시간으로 가정해 알고리즘 자체의 병렬성을 분석함
- Work와 Span을 분리해 총 비용과 이론적 최소 시간을 함께 평가함
- 동시 읽기·쓰기 허용 범위에 따라 표현 가능한 병렬 연산과 충돌 정책이 달라짐
- 실제 하드웨어에서는 캐시, 메모리 대역폭, 동기화 비용이 성능을 제한함

## Ⅲ. 종류 및 비교

| 판단 기준 | EREW | CREW | ERCW | CRCW |
|:---|:---|:---|:---|:---|
| 동시 읽기 | 배타적 읽기 | 공유 읽기 | 배타적 읽기 | 공유 읽기 |
| 동시 쓰기 | 배타적 쓰기 | 배타적 쓰기 | 정책 기반 공유 쓰기 | 정책 기반 공유 쓰기 |
| 주요 리스크 | 병렬성 제한 | 동일 주소 쓰기 제한 | 읽기 이득 없는 충돌 부담 | 충돌 규칙 복잡도 |

> 요약: 읽기는 EREW·ERCW가 배타적이고 CREW·CRCW가 공유임. 쓰기는 EREW·CREW가 배타적이고 ERCW·CRCW가 충돌 규칙으로 반영값을 정함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 프로세서 집합 | 동기 단계마다 연산과 메모리 접근을 수행하는 병렬 실행 단위 |
| 공유 메모리 | 모든 프로세서의 공용 저장 공간 |
| 동기 클록 | 단계별 병렬 연산의 동기 기준 |
| 충돌 정책 | 동일 주소 접근의 허용·선택 규칙 |
| Work·Span | 총 연산량과 최장 의존 경로의 병렬 성능 기준 |

```text
+-------------------+     동기 단계      +----------------+
| P1 · P2 · ... · Pp | ----------------> | 공유 메모리 M  |
+-------------------+                    +----------------+
          ^                                     |
          |          충돌 정책 적용             |
          +---- EREW · CREW · ERCW · CRCW <-----+
```

> 요약: PRAM은 동기 프로세서의 공유 메모리 접근·충돌 정책으로 병렬 실행 구조를 정의하고 Work·Span으로 비용과 병렬화 한계를 판단함.

## Ⅴ. 원리 및 절차 흐름도

```text
동시 읽기 처리 -> 로컬 연산 -> 동시 쓰기 처리 -> 동기화 배리어
```

1. **동시 읽기 처리**: EREW·ERCW는 프로세서마다 다른 주소만 배타적으로 읽음. CREW·CRCW는 같은 주소를 동시에 읽음
2. **로컬 연산**: 각 프로세서가 읽은 값으로 독립적인 연산을 수행함
3. **동시 쓰기 처리**: EREW·CREW는 프로세서마다 다른 주소에만 배타적으로 씀. ERCW·CRCW는 같은 주소에 동시에 쓸 때 우선순위·동일값·임의 선택 규칙으로 반영값을 정함
4. **동기화 배리어**: 모든 프로세서가 현재 스텝의 읽기·연산·쓰기를 마칠 때까지 대기한 뒤 다음 스텝으로 진행함

> 요약: PRAM은 스텝마다 변종별 정책으로 동시 읽기·쓰기를 처리하고 동기화 배리어로 다음 스텝을 시작함.

## Ⅵ. 실무 사례

1. 멀티코어 런타임은 유휴 스레드가 다른 스레드의 작업 큐에서 태스크를 가져오는 워크 스틸링을 적용함
2. 공유 메모리 집계는 코어별로 먼저 합산한 뒤 마지막에 결과를 병합함

## Ⅶ. 결론

- 병렬 알고리즘은 작업을 동시에 처리해 실행 시간을 줄이지만, 데이터 충돌과 동기화 비용을 통제해야 함
- 작업량보다 Span·동기화·메모리 경합이 병목이면 프로세서를 늘리지 말고 분할 단위와 데이터 배치를 다시 설계해야 함
