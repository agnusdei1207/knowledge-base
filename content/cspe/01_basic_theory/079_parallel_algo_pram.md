# 병렬 알고리즘 - PRAM 모델 (Parallel Algorithm PRAM)

## 1. 개요

- **정의/개념**: 병렬 알고리즘은 여러 처리기가 작업을 동시에 수행해 계산 시간을 줄이는 알고리즘이며, PRAM은 공유 메모리와 다수 프로세서를 가정한 이론적 병렬 계산 모델이다.
- **배경/필요성**: 단일 프로세서 성능 향상만으로 대규모 데이터를 처리하기 어렵기 때문에, 작업 분할과 동시 실행에 따른 성능 한계를 분석할 모델이 필요하다.

PRAM은 실제 하드웨어 세부를 제거하고 병렬성, 동기화, 메모리 접근 충돌을 분석하기 위한 추상 모델이다.

## 2. 특징 및 비교

| 구분 | EREW | CREW | CRCW |
|---|---|---|---|
| 읽기 | 배타 읽기 | 동시 읽기 가능 | 동시 읽기 가능 |
| 쓰기 | 배타 쓰기 | 배타 쓰기 | 동시 쓰기 가능 |
| 제약 | 가장 엄격 | 중간 | 가장 완화 |
| 분석 의미 | 충돌 없는 모델 | 읽기 공유 허용 | 쓰기 충돌 정책 필요 |

선택 기준은 병렬 시간, work, speedup, efficiency, memory contention이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Processor | 동시에 실행되는 계산 단위 | 병렬도 |
| Shared Memory | 모든 프로세서가 접근하는 메모리 | 접근 충돌 |
| Parallel Time | 병렬 실행 단계 수 | 성능 지표 |
| Work | 전체 연산량 | 비용 효율 |
| Synchronization | 단계별 동기화 | 병목 가능성 |

```text
문제분할 -> 프로세서별 병렬 실행 -> 동기화/메모리 접근 -> 결과병합
```

병렬 시간이 줄어도 전체 work가 과도하게 늘면 효율적인 병렬 알고리즘이라고 보기 어렵다.

## 4. 문제점 및 개선방안

1. **메모리 접근 충돌**
   - 여러 프로세서가 같은 위치를 읽거나 쓰면 모델별 제약이 달라진다.
   - **개선방안**: EREW/CREW/CRCW 조건을 명시하고 충돌 해결 규칙을 설계한다.

2. **병렬 오버헤드**
   - 작업 분할, 동기화, 통신 비용이 계산 이득을 상쇄할 수 있다.
   - **개선방안**: granularity 조정, work-efficient 알고리즘, locality 개선을 적용한다.

3. **이론 모델과 실제 하드웨어 차이**
   - PRAM은 cache, NUMA, 네트워크 비용을 단순화한다.
   - **개선방안**: 실제 환경에서는 벤치마크와 메모리 계층 분석을 병행한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 병렬 정렬 | 데이터를 분할해 정렬 후 병합 | speedup, work |
| 그래프 처리 | 정점·간선 단위 병렬 탐색 | throughput, contention |
| GPU 계산 | 데이터 병렬 연산으로 행렬·벡터 처리 | occupancy, memory bandwidth |

## 6. 결론

병렬 알고리즘과 PRAM 모델은 동시 실행으로 계산 시간을 줄이는 가능성과 한계를 분석하는 도구이다. PRAM 모델명 나열보다 동시 읽기·쓰기 규칙, work, speedup, 효율, 메모리 충돌을 함께 제시해야 병렬 설계 판단이 가능하다.
