## 미리 알고가기

- 병렬 알고리즘: 독립 작업을 여러 처리 장치에서 동시에 수행하도록 설계한 알고리즘임
- 병렬 공유 메모리 모델(PRAM): 동기식 공유 메모리와 다수 프로세서를 가정한 계산 모델임
- 총 연산량(Work): 모든 프로세서가 수행한 연산 수의 합임
- 최장 의존 시간(Span): 의존성 때문에 병렬화해도 줄지 않는 최장 경로 시간임
- 동시 접근 유형(EREW·CREW·CRCW): 공유 메모리의 동시 읽기·쓰기 허용 범위로 나눈 유형임
- 동시 쓰기 규칙(CRCW 충돌 규칙): 우선순위·동일값·임의 선택 중 하나로 반영할 값을 정함
- 리덕션 트리: 여러 부분 결과를 트리 형태로 병합해 하나의 결과를 만드는 병렬 구조임
- 워크 스틸링: 유휴 실행 단위가 다른 실행 단위의 대기 작업을 가져오는 동적 분배 방식임

## 작성 근거(검토용)

- 개요는 병렬 알고리즘과 PRAM을 함께 정의해 설계 대상과 분석 모델을 연결함
- 특징은 이상 모델, Work/Span, 접근 충돌, 실제 하드웨어 제약을 병렬 판단 기준으로 선정함
- Ⅲ은 동시 읽기·쓰기 허용 여부를 중심으로 PRAM 변종의 본질을 비교함
- 구조 도식은 리덕션의 단계별 병합 구조를 보여줌
- 부하 불균형과 공유 메모리 동기화는 병렬 성능을 제한하는 주요 조건임

## Ⅰ. 개요

- **정의/개념**: 병렬 알고리즘은 작업을 동시 실행 단위로 나누며, PRAM은 공유 메모리 병렬 계산의 이론적 한계를 분석하는 모델임
- **배경/필요성**: 대규모 연산의 처리 시간을 줄이기 위해 병렬성·동기화·메모리 접근 비용의 설계 기준이 필요함

## Ⅱ. 특징

- PRAM은 공유 메모리 접근을 단위 시간으로 가정해 알고리즘 자체의 병렬성을 분석함
- Work와 Span을 분리해 총 비용과 이론적 최소 시간을 함께 평가함
- 동시 읽기·쓰기 허용 범위에 따라 표현 가능한 병렬 연산과 충돌 정책이 달라짐
- 실제 하드웨어에서는 캐시, 메모리 대역폭, 동기화 비용이 성능을 제한함

## Ⅲ. 종류 및 비교

| 판단 기준 | EREW | CREW | CRCW |
|:---|:---|:---|:---|
| 동시 읽기 | 배타적 읽기 | 공유 읽기 | 공유 읽기 |
| 동시 쓰기 | 배타적 쓰기 | 배타적 쓰기 | 정책 기반 공유 쓰기 |
| 주요 리스크 | 병렬성 제한 | 동일 주소 쓰기 제한 | 충돌 규칙 복잡도 |

> 요약: EREW는 동시 읽기·쓰기를 배제하고, CREW는 동시 읽기만 허용하며, CRCW는 동시 쓰기 결과를 정책으로 결정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 핵심 설명 |
|:---|:---|
| 프로세서 집합 | 독립 작업의 병렬 실행 단위 |
| 공유 메모리 | 모든 프로세서의 공용 저장 공간 |
| 동기 클록 | 단계별 병렬 연산의 동기 기준 |
| 충돌 정책 | 동일 주소 접근의 허용·선택 규칙 |
| 리덕션 트리 | 부분 결과의 단계별 병합 구조 |

```text
[ 병렬 리덕션 ]
단계 0: x1  x2  x3  x4
단계 1: x1+x2   x3+x4
단계 2: (x1+x2)+(x3+x4)
```

> 요약: PRAM은 동기 프로세서가 공유 메모리에 접근하고 충돌 정책과 리덕션 트리로 병렬 결과를 결합함.

## Ⅵ. 실무 사례

1. 멀티코어 태스크 런타임은 워크 스틸링·동적 스케줄링을 적용하고 처리량·작업별 대기 시간으로 검증함
2. 공유 메모리 집계는 로컬 집계 후 병합하고 캐시 미스 횟수·동기화 대기 시간으로 검증함

## Ⅶ. 결론

- 병렬 알고리즘은 Work·Span·메모리 충돌을 기준으로 설계하고 캐시 미스·메모리 대역폭·동기화 대기로 이론적 속도 향상을 검증해야 함
