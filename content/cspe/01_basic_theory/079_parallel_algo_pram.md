## Ⅰ. 개요
- **정의**: 다수 프로세서가 공유 메모리에 동시 접근하여 병렬 연산을 수행하는 추상적 계산 모델임
- **배경/필요성**: 단일 코어 클럭 한계 도달 이후 멀티코어·GPU 환경에서 병렬 알고리즘의 이론적 분석 틀이 필수임
- **비유**: 여러 학생이 한 칠판(공유 메모리)을 동시에 보면서 각자 문제를 풀고 답을 적는 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PRAM 메모리 접근 모델 분류 | EREW / CREW / CRCW 의 Read·Write 동시성 차이 | 4가지 모델의 포함 관계(EREW⊂CREW⊂CRCW) 명시 |
| 병렬 복잡도와 한계 법칙 | Work(W)=T_1, Depth(D)=T_∞, 속도 향상=W/D | 암달 법칙 vs 구스타프슨 법칙 혼동 주의 |

> 요약: 공유 메모리 접근 규칙에 따라 PRAM을 분류하고, 병렬 복잡도(Work/Depth)로 알고리즘 효율을 분석하는 모델임

## Ⅱ. 구성요소
```text
+----------+     +-----------+     +-----------+
| Shared   | <-> | Processor | <-> | Access    |
| Memory   |     | Array P_i |     | Control   |
+----------+     +-----------+     +-----------+
     |                                   |
     +--- EREW / CREW / CRCW Rules ------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 공유 메모리 | 모든 프로세서가 O(1)에 접근 가능한 논리적 중앙 메모리 | 칠판 |
| 프로세서 배열 | 동일 클럭에 동기화되어 독립 연산을 수행하는 p개 프로세서 | 학생 |
| 접근 제어 규칙 | EREW(배타 R/W), CREW(동시 R/배타 W), CRCW(동시 R/W) | 발언 규칙 |
| Work/Depth 지표 | W=총 연산량, D=최장 의존 경로 길이, 최대 병렬도=W/D | 공수/공기 |

> 요약: 공유 메모리 + 프로세서 배열 + 접근 규칙 + Work/Depth 지표의 4요소로 병렬 알고리즘을 모델링함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| Partition| -> | Parallel | -> | Sync     | -> | Merge    |
+----------+    +----------+    +----------+    +----------+
```

1. **데이터 분할** — 크기 n의 입력을 p개 프로세서에 n/p 단위로 균등 배분함
2. **병렬 연산** — 각 프로세서가 접근 규칙(EREW/CREW/CRCW)에 따라 공유 메모리를 읽고 독립 연산 수행함
3. **동기화 장벽** — 모든 프로세서가 현재 단계를 완료할 때까지 Barrier 동기화 후 다음 단계 진입함
4. **결과 병합** — 로그 깊이(log p) 트리 구조로 부분 결과를 축약하여 최종 해를 공유 메모리에 기록함

> 요약: 분할 → 병렬 연산 → 동기화 → 로그 깊이 병합의 4단계로 O(n/p + log p) 시간 내 처리함

## Ⅳ. 문제점
- **동기화 오버헤드**: Barrier 동기화마다 O(log p) 지연 발생, 프로세서 수 증가 시 유휴 시간 비율 상승
- **암달 법칙 한계**: 순차 코드 비율 s가 존재하면 속도 향상 상한이 1/s로 제한되어 병렬화 효과 포화
- **실제 아키텍처 괴리**: PRAM의 O(1) 메모리 접근 가정은 캐시 계층·NUMA 지연·네트워크 대역폭을 미반영

> 요약: 동기화 지연, 순차 코드 비율 제약, 현실 하드웨어와의 괴리가 PRAM 모델의 3대 한계임

## Ⅴ. 개선방안
1. 단기: EREW 모델 기반 알고리즘 설계로 메모리 충돌 원천 방지 및 동기화 비용 최소화
2. 중기: BSP(Bulk Synchronous Parallel)·LogP 등 통신 비용을 반영한 현실적 병렬 모델로 전환
3. 장기: GPU SIMT + 분산 메모리(MPI) 하이브리드 자동 병렬화 컴파일러 적용

- **동기화 오버헤드**: 전역 Barrier → Lock-Free 자료구조 + 비동기 병렬화 (지표: 유휴 시간 < 5%)
- **암달 법칙 한계**: 고정 문제 크기 → 구스타프슨 법칙 기반 약한 스케일링 설계 (지표: 효율 ≥ 80%)
- **실제 아키텍처 괴리**: 추상 모델 → BSP/LogP 기반 지연·대역폭 파라미터 반영 (지표: 예측-실측 오차 < 15%)

> 요약: EREW 설계 → BSP/LogP 전환 → GPU 하이브리드 자동 병렬화로 이론과 실제의 격차를 해소함

## Ⅵ. 전망
- **향후 발전 방향**: Exascale(10^18 FLOPS) 시대에 수백만 코어 환경의 병렬 알고리즘 설계 수요 급증 전망
- **기술사적 판단**: PRAM은 병렬 복잡도 분석의 기초 모델로 유효하나, 실무에서는 BSP·MapReduce·CUDA 모델과 병행 활용이 필수임
- **기술사 제언**: Work-Depth 분석으로 병렬화 가치를 정량 평가한 후, 하드웨어 특성에 맞는 실용 모델을 선택해야 함
