## 미리 알고가기

- processor: 병렬 계산을 수행하는 논리 처리 단위임
- work: 전체 수행된 총 연산량임
- span: 병렬 실행 시 가장 긴 의존 경로 길이임

## Ⅰ. 개요

- **정의/개념**: 병렬 알고리즘은 여러 처리기가 동시에 작업을 수행하도록 문제를 분해하는 알고리즘이며, PRAM은 이를 이상화해 메모리 접근과 동기화를 분석하는 대표 모델임
- **배경/필요성**: 단일 코어 성능 향상에 한계가 있으므로 대규모 데이터 처리와 고성능 계산은 병렬성 활용이 필수임

## Ⅱ. 특징

- 문제를 독립 부분 작업으로 분해해 실행 시간을 단축함
- PRAM은 공유 메모리 기반 이상 모델이라 알고리즘 상한 분석에 유용함
- 병렬성 이득은 의존성, 통신, load imbalance에 의해 제한됨
- 실제 시스템은 메모리 충돌과 동기화 비용이 존재해 이론 속도와 차이가 남

## Ⅲ. 종류 및 비교

| 판단 기준 | EREW PRAM | CREW PRAM | CRCW PRAM |
|:---|:---|:---|:---|
| 동시 읽기 | 불가 | 가능 | 가능 |
| 동시 쓰기 | 불가 | 불가 | 가능 |
| 모델 단순성 | 높음 | 중간 | 낮음 |
| 표현력 | 보수적 | 일반적 | 가장 강함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 처리기 집합 | 동시에 명령을 수행하고 병렬도 수준을 결정함 |
| 공유 메모리 | 데이터 접근 공간이며 충돌 규칙이 중요함 |
| work | 총 연산량이며 효율성 기준임 |
| span | 가장 긴 직렬 경로이며 속도 향상 상한임 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 처리기 집합   | --> | 공유 메모리  | --> | work      | --> | span      |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문제분해 | --> | 작업할당 | --> | 동기병행 | --> | 병합/종료 |
+----------+     +----------+     +----------+     +----------+
```

1. **문제분해**: 독립 또는 약한 의존 작업으로 나눔
2. **작업할당**: 처리기별로 데이터를 분배함
3. **동기병행**: PRAM 규칙에 맞게 병렬 연산을 수행함
4. **병합/종료**: 부분 결과를 결합하고 완료함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 부하 불균형이 발생해 일부 처리기만 오래 일할 수 있음
   - 해결방안: 균등 분할과 work-stealing을 적용하고 processor utilization로 검증함
2. 문제: 메모리 충돌과 동기화가 병목이 되어 이론 모델보다 실제가 느려짐
   - 해결방안: local buffering과 reduction tree를 사용하고 synchronization overhead로 검증함
3. 문제: 병렬화 가능한 비율이 제한되어 순차 구간이 전체 속도를 묶음
   - 해결방안: Amdahl/Gustafson 관점으로 병목 구간을 줄이고 speedup으로 검증함

## Ⅶ. 적용 사례

- 대규모 정렬/검색에서는 병렬 prefix sum과 reduction을 사용하며, speedup과 scalability로 결과를 확인함
- 그래프 분석에서는 BFS, PageRank를 병렬 처리하며, 처리량으로 결과를 확인함
- GPU/멀티코어 연산에서는 병렬 행렬 계산에 활용하며, work efficiency와 latency로 결과를 확인함

## Ⅷ. 결론

병렬 알고리즘의 핵심은 처리기 수를 늘리는 것이 아니라 span을 줄이고 work를 낭비하지 않는 데 있으므로, 속도 향상은 의존성과 동기화 비용까지 같이 봐야 함.
