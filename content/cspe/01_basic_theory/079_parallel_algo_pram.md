## 미리 알고가기

- 병렬 처리($Parallel$ $Processing$): 하나의 연산 작업을 쪼개어 다수의 코어나 프로세서에서 동시에 처리하여 실행 속도를 높이는 기법임
- $PRAM$($Parallel$ $Random$ $Access$ $Machine$): 무한개의 프로세서와 동기화된 공유 메모리를 가졌다고 가정하는 이론적 병렬 연산 계산기 모델임
- 암달의 법칙($Amdahl's$ $Law$): 병렬화가 불가능한 순차적 영역의 비율로 인해, 아무리 프로세서 개수를 늘려도 전체 속도 향상($Speedup$)에 한계가 존재함을 증명한 법칙임
- 스팬($Span$): 알고리즘의 직렬적 데이터 의존성 관계에서 가장 긴 실행 경로이며, 무한한 프로세서를 가졌을 때의 최소 연산 도달 속도임

## Ⅰ. 개요

- **정의/개념**: 병렬 알고리즘은 하나의 연산 태스크를 여러 개의 독립된 서브 작업으로 나누어 복수의 프로세서가 동시에 병렬 실행하도록 흐름을 제어하는 방식이며, $PRAM$은 하드웨어적 물리 장벽을 배제하고 알고리즘의 본질적 병렬 한계를 수학적으로 규명하기 위한 이상적 모델임
- **배경/필요성**: 단일 CPU의 물리적 클록 주파수 한계(발열 등)로 인한 클록 한계 장벽($Power$ $Wall$)을 극복하고, 대규모 행렬 계산이나 시뮬레이션을 초고속으로 완수하기 위해 다중 코어 협업 아키텍처가 필수적으로 요구됨

## Ⅱ. 특징

- PRAM 모델은 프로세서 간의 물리적 통신 지연(지연시간 $0$)이나 네트워크 대역폭 제한이 전혀 없는 동기식 공유 메모리 가상 하드웨어를 전제로 동작함
- 알고리즘 복잡도를 연산의 총합인 $Work$와 순차적 의존 경로인 $Span$(또는 깊이)의 두 가지 축으로 분리하여 병렬 효율성($Speedup$)의 이론적 상한을 분석함
- 메모리 접근 시 여러 프로세서가 동일한 번지에 동시에 읽거나 쓸 수 있는 범위에 따라 세부 아키텍처 모델(EREW $\rightarrow$ CRCW)로 변형 분류됨

## Ⅲ. PRAM 메모리 접근 방식 종류 및 비교

| 모델 약어 | 명칭 (Full Name) | 동시 읽기 (Read) | 동시 쓰기 (Write) | 특징 및 연산 난이도 |
|:---|:---|:---|:---|:---|
| **EREW** | $Exclusive$ $Read$ $Exclusive$ $Write$ | 불가능 (오직 1개 노드만) | 불가능 (독점 쓰기) | 가장 엄격하고 하드웨어 구현이 현실적인 최하위 모델임 |
| **CREW** | $Concurrent$ $Read$ $Exclusive$ $Write$ | 동시 허용 | 불가능 (독점 쓰기) | 다수의 프로세서가 한 값을 동시 참조 가능하여 일반적임 |
| **CRCW** | $Concurrent$ $Read$ $Concurrent$ $Write$ | 동시 허용 | 동시 허용 | 동일 번지 쓰기 충돌($Collision$) 관리 정책이 필수적임 |

*CRCW 충돌 정책: 공통 값만 쓰기(Common), 임의 쓰기(Arbitrary), 최댓값 우선(Priority), 다 더하기(Sum) 등이 존재함.*

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프로세서 배열 ($P$) | 병렬 연산을 병렬성으로 나누어 수행할 수 있는 다중 CPU 코어들의 가상 논리 묶음임 |
| 공유 메모리 | 프로세서들이 임의로 접근할 수 있는 무제한의 중앙 공용 메모리 테이블임 |
| 글로벌 클록 | 모든 프로세서가 일체 어긋남 없이 한 클록 단위로 명령을 받아 수행하도록 강제하는 동기화 장치임 |
| 리덕션 트리 | 데이터를 병렬 합산할 때 부채꼴 모양으로 반씩 모아 합치는 연산 구조(EREW 등에서 필수)임 |

```text
[ 병렬 Prefix Sum (Reduction) 구조 예시 ]
  [1]     [2]     [3]     [4]     (Step 0)
    \     /         \     /
    [ 1+2 ]         [ 3+4 ]       (Step 1: O(log N) Span으로 병렬 수렴)
       \               /
       [ (1+2) + (3+4) ]          (Step 2: 최종 리덕션 결과 도출)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 태스크 분할  | --> | 프로세서 분배| --> | 공유메모리독/쓰| --> | 최종 결과취합|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **병렬성 추출** — 대형 태스크의 자료 의존성($Data$ $Dependency$) 관계를 분석하여 서로 연산에 방해를 주지 않는 병렬 블록을 나눔
2. **프로세스 매핑** — 스케줄러가 개별 서브 태스크를 $PRAM$ 프로세서 $P_i$들에 고르게 분산 배치하여 연산량을 균등화($Load$ $Balancing$)함
3. **공유 메모리 연산** — EREW, CREW 등 약속된 $PRAM$ 버스 규칙에 의거하여 공유 메모리의 값을 읽고 연산 결과를 다시 메모리에 저장함
4. **글로벌 동기화** — 배리어($Barrier$)나 리덕션 트리 구조를 이용해 모든 프로세서의 계산 완료 시점을 맞추고 최종 취합 결과를 생성함

## Ⅵ. 실무 적용 및 유의점

1. 병렬 알고리즘 구현 시 특정 프로세서에만 연산이 쏠리고 다른 프로세서는 노는 '부하 불균형($Load$ $Imbalance$)'이 일어나면 병렬 효율이 급감하므로, 남는 프로세서가 바쁜 노드의 일을 뺏어가는 '워크 스틸링($Work-stealing$)' 스케줄링을 도입해야 함
2. 실제 멀티코어나 $GPU$(CUDA 등) 환경은 PRAM의 상상과 달리 캐시 일관성($Cache$ $Coherency$)과 동기화 장벽 락($Lock$)의 하드웨어 오버헤드가 크므로, 로컬 메모리 캐싱을 통해 공유 버스 트래픽을 최소화하도록 코드를 최적화해야 함

## Ⅶ. 결론

- PRAM 모델은 병렬 계산의 수학적 한계인 스팬과 총 연산량의 한계를 판별하는 기본 렌즈이며, 설계자는 암달의 법칙에 근거한 순차 영역 제거와 하드웨어 물리 통신 지연의 타협을 통해 진정한 분산 고속 처리 엔진을 구축해야 함
