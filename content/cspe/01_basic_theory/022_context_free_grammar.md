## 미리 알고가기

- 단말 기호($\Sigma$): 더 이상 치환되지 않고 실제 입력에 나타나는 기호임
- 비단말 기호($N$): 생성 규칙에 의해 다른 기호열로 바뀌는 문법 변수임
- 생성 규칙($P$): 좌변 비단말을 우변 기호열로 치환하는 규칙임
- 구문 분석 트리(Parse Tree): 생성 규칙 적용 순서를 계층 구조로 나타낸 트리임
- 모호성: 하나의 문자열에 두 개 이상의 구문 분석 트리가 만들어지는 성질임
- 푸시다운 오토마타: 유한 상태에 스택을 더해 중첩 구조를 인식하는 모델임

## 작성 근거(검토용)

- 개요는 Type-2 규칙 제약과 계층 문자열 생성이라는 두 축을 함께 제시해 정규 문법과 구분함
- 특징은 규칙 적용·재귀 표현·구문 분석 트리·스택 대응으로 이어지게 배치해 뒤 절의 구조와 연결함
- Ⅲ은 촘스키 계층 안에서 CFG의 위치를 보여주어 표현력과 비용의 균형을 판단하게 함
- Ⅳ와 Ⅴ는 문법 요소가 구문 분석 트리와 검증 절차로 이어지는 흐름을 답안 구조로 고정함
- 실무 유의점은 CFG의 장점보다 실제 오류 원인인 좌재귀, 모호성, 정규식 오용을 중심으로 작성함

## Ⅰ. 개요

- **정의/개념**: 문맥 자유 문법은 모든 생성 규칙의 좌변이 단일 비단말 기호인 Type-2 형식 문법이며, 단말·비단말 조합으로 계층적 문자열을 생성함
- **배경/필요성**: 괄호·블록·태그의 짝과 깊이를 표현하기 위해 정규 언어보다 강한 문법 구조가 필요함

## Ⅱ. 특징

- 좌변이 항상 비단말 1개이므로 주변 문맥과 무관하게 규칙을 적용할 수 있음
- 재귀 규칙으로 괄호 짝과 블록 중첩 같은 계층 구조를 표현함
- 구문 분석 트리를 통해 문장의 구조를 보이지만, 모호한 문법은 해석 결과가 갈림
- 스택을 사용하는 푸시다운 오토마타와 대응되어 중첩 깊이를 처리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 문법 | 문맥 자유 문법 | 문맥 의존 문법 |
|:---|:---|:---|:---|
| 촘스키 등급 | Type-3 | Type-2 | Type-1 |
| 규칙 우변 | 단말 뒤 비단말 최대 1개 | 임의의 기호열 | 좌변 길이보다 줄지 않음 |
| 필요한 기억 | 유한 상태 | 스택 | 선형 제한 메모리 |
| 표현 대상 | 토큰 패턴 | 구문 중첩 | 문맥 제약 |
| 대표 활용 | 어휘 분석 | 구문 분석 | 자연어 일부 제약 |

> 요약: 문맥 자유 문법은 정규 문법보다 강하고, 실제 컴파일러 구문 분석에 많이 쓰이는 실용적 균형점임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비단말 집합($N$) | 문장 구조를 단계적으로 펼치는 문법 변수의 집합임 |
| 단말 집합($\Sigma$) | 최종 문자열에 남는 실제 토큰 집합임 |
| 생성 규칙($P$) | $A \rightarrow \alpha$ 형태로 비단말 하나를 기호열로 치환함 |
| 시작 기호($S$) | 전체 문장 구조를 생성하는 최상위 비단말임 |
| 구문 분석 트리 | 규칙 적용 결과를 부모-자식 관계로 보여주어 해석 기준이 됨 |

```text
+---------+     +-------------+     +------------+
| 시작 기호 | --> | 생성 규칙 적용 | --> | 구문 분석 트리 |
+---------+     +-------------+     +------------+
                                      |
                                      v
                                 +----------+
                                 | 토큰열 검증 |
                                 +----------+
```

> 요약: CFG는 생성 규칙을 구문 분석 트리로 펼쳐 토큰열의 계층 구조를 검증함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 시작 기호  | --> | 비단말 치환  | --> | 트리 구성   | --> | 문장 판정  |
+----------+     +----------+     +----------+     +----------+
```

1. **문법 설정**: 시작 기호, 단말, 비단말, 생성 규칙을 정의함
2. **규칙 적용**: 현재 문장형의 비단말을 선택하고 우변 기호열로 치환함
3. **구조 생성**: 치환 관계를 구문 분석 트리에 기록해 계층 구조를 유지함
4. **문장 판정**: 모든 기호가 단말이면 문장을 인정하고, 파싱 실패 시 거부함

> 요약: 비단말 치환이 모두 단말 토큰으로 수렴하면 문법에 맞는 문장으로 판정함.

## Ⅵ. 실무 적용 및 유의점

1. 컴파일러 구문 분석은 CFG로 식과 블록을 정의하되, 좌재귀와 모호성이 파싱 충돌을 만들면 우선순위 규칙과 문법 변환을 적용하고 충돌 수로 확인함
2. XML·HTML 같은 중첩 문서는 정규식 대신 CFG 계열 파서로 처리하고, 태그 짝 오류와 트리 생성 실패를 구조 무결성 지표로 확인함

## Ⅶ. 결론

- 문맥 자유 문법은 중첩 구조를 문법과 트리로 제어하는 모델이므로 모호성은 우선순위·결합 규칙으로 통제하고 좌재귀는 파서 방식에 맞게 변환해야 함
