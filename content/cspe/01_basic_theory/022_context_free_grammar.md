## 미리 알고가기

- 비단말 기호: 다른 기호열로 치환되는 문법 변수임
- 파스 트리: 문법 규칙이 적용된 계층 구조를 시각화한 결과임
- PDA: 문맥 자유 언어를 인식하는 스택 기반 오토마타임

## Ⅰ. 개요

- **정의/개념**: 문맥 자유 문법은 생성 규칙의 좌변이 항상 하나의 비단말인 문법으로, 재귀와 중첩 구조를 표현해 문맥 자유 언어를 생성하는 형식 체계임
- **배경/필요성**: 프로그래밍 언어, 수식, 괄호 구조처럼 계층적 문장을 정의하려면 정규 언어보다 높은 표현력이 필요함

## Ⅱ. 특징

- 규칙 $A \rightarrow \gamma$ 형태로 정의되어 구조 서술이 명확함
- 스택 기반 인식이 가능해 중첩과 재귀를 자연스럽게 표현함
- 파스 트리를 통해 문장 구조와 의미 분석의 기반을 제공함
- 모호한 문법은 하나의 문장에 여러 해석을 만들 수 있어 설계 통제가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 문법 | 문맥 자유 문법 |
|:---|:---|:---|
| 생성 규칙 | 선형 형태 제한 | 좌변 1개 비단말 |
| 표현력 | 반복, 단순 패턴 | 중첩, 재귀, 수식 |
| 인식 모델 | FA | PDA |
| 대표 적용 | Lexer | Parser |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비단말 $V$ | 구조 단위를 추상화하고 문장 계층을 표현함 |
| 단말 $\Sigma$ | 최종 출력 기호이며 실제 입력 토큰과 대응됨 |
| 생성 규칙 $P$ | 비단말을 다른 기호열로 치환하고 언어 구조를 정의함 |
| 시작 기호 $S$ | 문장 생성의 출발점이며 전체 문법의 루트임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문법정의 | --> | 토큰입력 | --> | 규칙적용 | --> | 구조판정 |
+----------+     +----------+     +----------+     +----------+
```

1. **문법정의**: 문장 구조를 생성 규칙 집합으로 설계함
2. **토큰입력**: Lexer가 만든 토큰열을 파서에 전달함
3. **규칙적용**: 파서가 규칙을 적용해 파스 트리를 구성함
4. **구조판정**: 허용 구조면 수용하고 의미 분석 단계로 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 문법 모호성이 발생해 같은 입력이 여러 파스 트리를 만들 수 있음
   - 해결방안: 우선순위, 결합 방향, 문법 리팩터링으로 해석을 단일화하고 shift/reduce conflict 수로 검증함
2. 문제: 좌재귀는 일부 파서에서 무한 재귀를 유발해 LL 계열 파서가 직접 처리하지 못함
   - 해결방안: 좌재귀 제거와 좌인수분해를 적용하고 파서 생성 성공 여부로 검증함
3. 문제: 문법이 커질수록 유지보수가 어려워 규칙 간 의존성이 복잡해짐
   - 해결방안: 표현식, 선언, 제어문 단위로 모듈화하고 규칙 변경 영향 범위로 검증함

## Ⅶ. 적용 사례

- 프로그래밍 언어 파서: 식, 문장, 블록 구조를 CFG로 정의함, 확인 지표는 파싱 정확도와 충돌 수임
- 수식 처리 엔진: 괄호와 연산자 우선순위를 규칙으로 통제함, 확인 지표는 AST 생성률임
- DSL 설계: 업무 규칙을 도메인 문법으로 제한함, 확인 지표는 문법 확장성 및 오류 메시지 품질임

## Ⅷ. 결론

문맥 자유 문법은 계층적 문장을 정의하는 기본 도구이므로, 표현력 확보와 파싱 가능성 사이에서 모호성 통제와 파서 친화적 구조 설계가 핵심임.
