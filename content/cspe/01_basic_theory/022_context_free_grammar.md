## 미리 알고가기

- 단말 기호($\Sigma$): 더 이상 치환되지 않고 실제 입력에 나타나는 기호임
- 비단말 기호($N$): 생성 규칙에 의해 다른 기호열로 바뀌는 문법 변수임
- 생성 규칙($P$): 좌변 비단말을 우변 기호열로 치환하는 규칙임
- 구문 분석 트리(Parse Tree): 생성 규칙 적용 순서를 계층 구조로 나타낸 트리임
- 모호성: 하나의 문자열에 두 개 이상의 구문 분석 트리가 만들어지는 성질임
- 푸시다운 오토마타: 유한 상태에 스택을 더해 중첩 구조를 인식하는 모델임
- 선형 제한 오토마타: 입력 길이에 비례하는 테이프 안에서 문맥 의존 언어를 인식하는 모델임
- 촘스키 계층(Chomsky Hierarchy): Type-3은 정규, Type-2는 문맥 자유, Type-1은 문맥 의존 문법임
- 시작 기호($S$): 전체 문자열 생성을 시작하는 비단말 기호임

## 작성 근거(검토용)

- 개요는 Type-2 규칙 제약과 계층 문자열 생성이라는 두 축을 함께 제시해 정규 문법과 구분함
- 특징은 규칙 적용·재귀 표현·구문 분석 트리·스택 대응으로 이어지게 배치해 뒤 절의 구조와 연결함
- Ⅲ은 생성 규칙, 인식 모델, 표현 범위로 문법 계층의 핵심 차이를 판단하게 함
- Ⅳ와 Ⅴ는 문법 요소가 구문 분석 트리와 단말 문자열 생성 절차로 이어지는 흐름을 답안 구조로 고정함
- 문맥 자유 문법의 장점보다 오류 원인인 좌재귀·모호성을 중심으로 작성함

## Ⅰ. 개요

- **정의/개념**: 문맥 자유 문법(CFG)은 모든 생성 규칙의 좌변이 단일 비단말 기호인 Type-2 형식 문법이며, 재귀 규칙으로 계층적 구문을 생성함
- **배경/필요성**: 괄호·블록·태그의 중첩을 표현하고 인식하기 위해 재귀 규칙과 스택 기반 인식 모델이 필요함

## Ⅱ. 특징

- 좌변이 항상 비단말 1개이므로 주변 문맥과 무관하게 규칙을 적용할 수 있음
- 재귀 규칙으로 괄호 짝과 블록 중첩 같은 계층 구조를 표현함
- 구문 분석 트리를 통해 문장의 구조를 보이지만, 모호한 문법은 해석 결과가 갈림
- 스택을 사용하는 푸시다운 오토마타와 대응되어 중첩 깊이를 처리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 문법 | 문맥 자유 문법 | 문맥 의존 문법 |
|:---|:---|:---|:---|
| 생성 규칙 형태 | $A \rightarrow aB$ 또는 $A \rightarrow a$ | $A \rightarrow \alpha$ | 문맥 포함 좌변 $\rightarrow$ 비축약 기호열 |
| 대응 인식 모델 | 유한 오토마타 | 푸시다운 오토마타 | 선형 제한 오토마타 |
| 표현 범위 | 토큰의 반복 패턴 | 재귀적 구문 중첩 | 주변 기호의 문맥 제약 |

> 요약: CFG는 비단말을 기호열로 치환해 중첩 구조를 생성하고 PDA는 중첩 구조를 스택으로 인식함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 비단말 집합($N$) | 문장 구조를 전개하는 문법 변수 집합 |
| 단말 집합($\Sigma$) | 최종 문자열에 남는 토큰 집합 |
| 생성 규칙($P$) | $A \rightarrow \alpha$ 형태의 비단말 치환 규칙 |
| 시작 기호($S$) | 전체 문장 구조의 시작 비단말 |

> 요약: CFG는 시작 기호와 생성 규칙으로 구문 구조와 단말 문자열을 정의함.

## Ⅴ. 원리 및 절차 흐름도

```text
시작 기호 선택 → 적용할 생성 규칙 선택 → 비단말 치환
                                      ├─ 비단말 남음 → 규칙 선택 반복
                                      └─ 단말만 남음 → 문자열·파스 트리 확정
```

1. **문법 설정**: 시작 기호, 단말, 비단말, 생성 규칙을 정의함
2. **규칙 적용**: 현재 문장형의 비단말을 선택하고 우변 기호열로 치환함
3. **구조 생성**: 치환 관계를 구문 분석 트리에 기록해 계층 구조를 유지함
4. **단말열 확정**: 비단말이 모두 단말로 치환되면 생성 문장을 확정함

> 요약: 비단말 치환을 구문 분석 트리에 기록하고 단말 문자열을 확정함.

## Ⅵ. 실무 사례

1. 하향식 컴파일러 파서는 좌재귀를 제거해 예측 파싱이 가능한 문법으로 바꿈
2. 구성 언어 파서는 CFG로 괄호·블록의 중첩을 분석해 구문 트리를 생성함

## Ⅶ. 결론

- 문맥 자유 문법은 재귀 규칙으로 중첩 구조를 표현하며, 모호성과 파서가 처리할 수 없는 문법 형태를 통제해야 함
- 문법은 파서 구현의 입력 계약이므로 언어 확장 전에 충돌·모호성을 검사하고 기존 구문 트리 호환성을 유지해야 함
