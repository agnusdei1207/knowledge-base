## 미리 알고가기

- 비단말 기호 ($N$): 생성 규칙에 의해 다른 기호열로 치환될 수 있는 중간 매개체임
- 단말 기호 ($\Sigma$): 더 이상 치환되지 않는 최종 문자열로, 실제 입력 텍스트를 구성하는 토큰임
- 생성 규칙 ($P$): 좌변의 비단말 기호를 우변의 기호열로 바꾸는 치환 규칙의 집합임
- 파스 트리 ($Parse$ $Tree$): 문법 규칙이 적용되어 문장이 생성되는 과정을 계층적인 트리 구조로 나타낸 것임
- 푸시다운 오토마타 (PDA): 유한 상태 기계에 스택($Stack$) 메모리를 추가하여 중첩 구조를 인식하는 모델임

## Ⅰ. 개요

- **정의/개념**: 문맥 자유 문법(CFG)은 모든 생성 규칙의 좌변이 단일 비단말 기호($A \rightarrow \alpha$)로 구성되어 주변 문맥과 상관없이 치환이 가능하며, 우변에는 단말과 비단말의 임의 조합을 허용하는 형식 문법(Type-2)임
- **배경/필요성**: 정규 문법은 괄호의 중첩이나 블록 구조처럼 '짝'을 맞추기 위해 이전 상태를 기억해야 하는 재귀적 구조를 표현할 수 없으므로, 프로그래밍 언어의 복잡한 구문을 정의하기 위한 상위 수준의 문법 체계가 필요함

## Ⅱ. 특징

- 생성 규칙의 좌변이 항상 하나의 비단말 기호이므로 규칙 적용 시 주변의 영향을 받지 않는 '문맥 자유' 특성을 가지며, 이는 파싱($Parsing$) 알고리즘의 설계를 단순화함
- 재귀적 정의($A \rightarrow \alpha A \beta$)를 통해 무한한 깊이의 중첩 구조를 표현할 수 있으며, 이 문법이 정의하는 언어는 스택 메모리를 사용하는 푸시다운 오토마타($PDA$)로 인식이 가능함
- 하나의 문장에 대해 두 개 이상의 파스 트리가 만들어지는 '모호성($Ambiguity$)'이 발생할 수 있으므로, 문법 설계 시 연산자 우선순위와 결합 법칙을 명확히 정의해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 문법 (Type-3) | 문맥 자유 문법 (Type-2) |
|:---|:---|:---|
| **생성 규칙 제약** | $A \rightarrow aB$ 또는 $A \rightarrow a$ | $A \rightarrow \alpha$ (좌변은 오직 비단말 1개) |
| **기억 메커니즘** | 유한 상태 정보 ($O(1)$ 메모리) | 스택 구조 ($LIFO$ 메모리) |
| **표현 능력** | 단순 반복 및 선택 패턴 | 재귀, 중첩, 괄호 짝 맞추기 |
| **인식 모델** | 유한 오토마타 ($DFA/NFA$) | 푸시다운 오토마타 ($PDA$) |
| **실무 활용** | 어휘 분석 ($Lexical$ $Analysis$) | 구문 분석 ($Syntax$ $Analysis$) |

> 요약: 정규 문법은 토큰 패턴을, 문맥 자유 문법은 문장의 계층 구조를 정의하는 데 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 기호 | 설명 |
|:---|:---|:---|
| 비단말 집합 | $N$ | 치환 가능한 가변 기호들의 유한 집합임 |
| 단말 집합 | $\Sigma$ | 문장의 최종 형태를 이루는 고정 기호들의 유한 집합임 |
| 생성 규칙 | $P$ | $A \rightarrow \alpha$ 형태의 치환 규칙 집합 ($A \in N, \alpha \in (N \cup \Sigma)^*$)임 |
| 시작 기호 | $S$ | 문장 생성이 시작되는 고유한 비단말 기호 ($S \in N$)임 |

```text
[ CFG 생성 규칙 예시 ]
S -> aSb | ε
- S에서 시작하여 a와 b 사이에 다시 S를 넣는 재귀 구조임
- 생성 가능 문자열: ab, aabb, aaabbb ... (a^n b^n)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 시작 기호 진입| --> | 규칙 선택/치환| --> | 재귀적 전개   | --> | 단말 기호 완성|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **시작 설정** — 문법의 최상위 루트인 시작 기호($S$)를 현재의 파생 문자열로 설정함
2. **비단말 선택** — 현재 문자열에 포함된 비단말 기호를 찾아, 해당 기호를 좌변으로 하는 생성 규칙 중 하나를 선택함
3. **치환 및 전개** — 선택된 규칙의 우변 기호열로 비단말을 교체하며, 문자열에 비단말이 남아있는 동안 이 과정을 재귀적으로 반복함
4. **파생 종료** — 문자열이 오직 단말 기호들로만 구성되어 더 이상 치환할 비단말이 없으면 파생을 종료하고 최종 문장을 완성함

## Ⅵ. 실무 적용 및 유의점

1. 컴파일러 설계 시, 문법 규칙 우변의 가장 처음에 자기 자신이 다시 나오는 '좌재귀($Left$ $Recursion$)'가 포함되면 하향식 파서가 무한 루프에 빠질 수 있으므로, 문법을 우재귀 형태로 변환하거나 상향식 파싱 알고리즘을 적용하여 파서의 안정성을 확보해야 함
2. $HTML$이나 $XML$과 같이 중첩 구조가 명확한 문서 형식을 파싱할 때 정규식(정규 문법)을 사용하면 중첩 깊이 오류를 감지하지 못하므로, 반드시 CFG 기반의 $DOM$ 트리 파서를 사용하여 문서의 구조적 무결성을 검증해야 함

## Ⅶ. 결론

- 문맥 자유 문법은 프로그래밍 언어와 데이터 형식의 계층적 구조를 정의하는 표준 논리 체계이며, 설계자는 모호성과 재귀 구조를 정밀하게 제어하여 신뢰성 있는 구문 분석 시스템을 구축해야 함
