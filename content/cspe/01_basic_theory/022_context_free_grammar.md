# 문맥 자유 문법 (Context-Free Grammar)

## 1. 개요

- **정의/개념**: 문맥 자유 문법(Context-Free Grammar, CFG)은 비단말 기호 하나를 좌변으로 두는 생성 규칙으로 중첩 가능한 문자열 구조를 정의하는 형식 문법이다.
- **배경/필요성**: 프로그래밍 언어의 괄호, 블록, 수식처럼 계층적 구조는 정규 언어만으로 표현하기 어렵기 때문에 스택 기반 파싱이 가능한 문법 모델이 필요하다.

CFG의 핵심은 문자열을 단순 패턴으로 보는 것이 아니라 파스 트리로 표현되는 계층 구조로 해석하는 것이다.

## 2. 특징 및 비교

| 구분 | 정규 문법 | 문맥 자유 문법 |
|---|---|---|
| 표현 대상 | 단순 패턴, 토큰 | 중첩 구조, 구문 |
| 인식기 | 유한 오토마타 | Pushdown Automata |
| 메모리 | 유한 상태 | 스택 사용 |
| 산출물 | 수용 여부 중심 | 파스 트리 생성 |
| 대표 활용 | 어휘 분석 | 구문 분석 |

CFG 선택 기준은 중첩 구조 표현 필요성, 파싱 가능성, 모호성 여부, 구현 복잡도이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| V | 비단말 기호 집합 | 문법 구조 단위 |
| T | 단말 기호 집합 | 실제 입력 토큰 |
| P | 생성 규칙 집합 | 구조 생성 규칙 |
| S | 시작 기호 | 파싱 시작점 |
| Parse Tree | 생성 과정의 트리 표현 | 구문 구조 검증 |

```text
----------+      +----------+      +----------+      +----------+
| 토큰열   | ---> | 생성규칙 | ---> | 파스트리 | ---> | 구문판정 |
+----------+      +----------+      +----------+      +----------+
```

구성요소가 파스 트리로 이어지므로, CFG의 정확성은 생성 규칙이 의도한 구문 구조만 만들도록 설계되었는지에 달려 있다.

## 4. 문제점 및 개선방안

1. **문법 모호성**
   - 하나의 문자열에 여러 파스 트리가 가능하면 의미 분석 결과가 달라질 수 있다.
   - **개선방안**: 우선순위·결합 규칙을 명시하거나 문법을 재작성한다.

2. **좌재귀와 파서 제약**
   - LL 파서는 좌재귀 문법을 직접 처리하기 어렵다.
   - **개선방안**: 좌재귀 제거, left factoring, LR 계열 파서 적용을 검토한다.

3. **정규 언어와 역할 혼동**
   - 토큰 수준 처리를 CFG로 모두 처리하면 파서가 불필요하게 복잡해진다.
   - **개선방안**: 어휘 분석은 정규 언어, 구문 분석은 CFG로 역할을 분리한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 컴파일러 구문 분석 | 프로그래밍 언어 문법을 CFG로 정의하고 파스 트리 생성 | 파싱 성공률, 오류 위치 |
| DSL 설계 | 업무 규칙 언어의 문법과 의미 구조 정의 | 문법 충돌 수, 사용자 오류율 |
| 데이터 포맷 검증 | JSON, SQL 일부 구문 같은 계층 구조 검증 | 구문 오류 검출률 |

## 6. 결론

문맥 자유 문법은 정규 언어가 다루기 어려운 중첩 구조를 표현하는 핵심 모델이다. CFG 답안은 `G=(V,T,P,S)` 정의에서 멈추지 않고 파스 트리, 모호성, 파서 선택까지 연결해야 실무 구현 관점이 살아난다.
