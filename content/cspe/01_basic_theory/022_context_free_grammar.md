# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 문맥 자유 문법(CFG)은 **촘스키 위계** Type 2에 해당하는 **형식 언어**로, 좌변에 단일 비단말 기호만 허용하는 생성 규칙(A → α)으로 정의되며 **푸시다운 오토마타(PDA)**로 인식 가능한 언어 클래스이다.
- **왜 필요한가**: 프로그래밍 언어의 괄호 짝 맞추기, if-else 중첩, 수식 우선순위 같은 **재귀적 계층 구조**는 정규 언어(Type 3, 021 참조)의 유한 오토마타로는 표현·인식이 불가능하며, 스택(Stack) 메모리를 갖춘 문법 모델이 필요하다.
- **핵심 직관**: "A는 B와 C로 이루어진다"라는 규칙에서, A의 주변에 무엇이 오든 A는 항상 B와 C로 전개된다 — '문맥과 무관하게 치환'되므로 '문맥 자유'라 부른다.

## 핵심 용어 정리 (내부에 등장하는 것들)

CFG의 4튜플 구성요소와 파싱 관련 개념을 세운다. 정규 언어(Type 3)와의 차이는 021, 오토마타 기초는 020 참조.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 촘스키 위계 Type 2 (상위 키워드) | 좌변 단일 비단말 제약의 문법으로 정의되는 언어 계층 | 괄호·블록 중첩이 가능한 문법 등급 |
| 비단말 기호 (Non-terminal, V) | 다른 기호열로 전개(치환)되는 중간 변수 | 문장 구조의 뼈대: \<문장\>, \<수식\> |
| 단말 기호 (Terminal, T) | 더 이상 전개되지 않는 최종 어휘 토큰 | if, (, ), 123 같은 실제 단어 |
| 생성 규칙 (Production, P) | A → α 형태의 치환 규칙 (A ∈ V, α ∈ (V ∪ T)*) | \<수식\> → \<항\> + \<항\> |
| 시작 기호 (Start Symbol, S) | 문법 파생이 시작되는 최초 비단말 기호 | 구문 트리의 루트 노드 |
| 푸시다운 오토마타 (PDA) | 유한 상태 + 스택(LIFO)을 갖춘 인식 기계 | 괄호 개수를 세는 기억력이 있는 자판기 |
| 추상 구문 트리 (AST) | 생성 규칙 적용 순서를 트리로 표현한 프로그램 구조 | 소스 코드의 계층적 골격 |
| 모호성 (Ambiguity) | 동일 문자열에 2개 이상의 서로 다른 파싱 트리가 존재하는 상태 | 1+2*3을 두 가지로 해석 가능 |
| LL / LR 파서 | 하향식(LL)·상향식(LR)으로 CFG를 결정론적 O(N)에 파싱하는 알고리즘 | 074 참조 |

## 깊이 이해
- **배경·문제의식**: 정규 언어(021)는 유한 오토마타에 메모리가 없어 a^n b^n(괄호 n개 열고 n개 닫기) 같은 재귀 구조를 인식할 수 없다. 프로그래밍 언어의 중첩 블록·수식 우선순위를 표현하려면, "열린 것의 개수를 기억"할 스택이 필요한 상위 문법이 필요했다.
- **작동 원리**:
  - **생성 규칙의 제약**: CFG의 핵심 제약은 좌변이 반드시 '단일 비단말 기호 하나'라는 점이다. 즉 αAβ → αγβ처럼 주변 문맥(α, β)을 조건으로 삼지 않고, 오직 A → γ로 독립 치환한다.
  - **파생(Derivation)**: 시작 기호 S에서 생성 규칙을 반복 적용해 단말 기호열을 만들어내는 과정이다. 이 과정을 트리로 표현한 것이 파싱 트리(Parse Tree)이고, 불필요한 중간 노드를 제거한 것이 AST이다.
  - **PDA 인식 원리**: 여는 괄호를 스택에 Push하고 닫는 괄호에 Pop하여 짝을 맞춘다. 입력 종료 시 스택이 비어 있으면 Accept이다.
  - **결정론적 CFG (DCFG)**: 범용 CFG 파싱은 O(N³)(CYK, Earley)이지만, 컴파일러는 선독(Lookahead) 토큰으로 백트래킹 없이 O(N)에 파싱 가능한 결정론적 부분집합(LL(k), LR(k))을 사용한다.
- **비유**: 식당 메뉴판에서 "세트 A = 버거 + 감튀 + 콜라"라면, 앞뒤에 어떤 주문이 오든 세트 A는 항상 저 구성으로 전개된다 — 문맥에서 자유로운 치환이다.
- **구체 예시**:
  - 균형 괄호 문법: S → (S) | SS | ε — 이 규칙으로 "(())", "()()" 등 모든 균형 괄호 문자열을 생성할 수 있다.
  - 수식 문법: E → E + T | T, T → T * F | F, F → (E) | id — 연산자 우선순위(곱셈 > 덧셈)와 괄호 중첩을 문법 구조로 강제한다.
- **흔한 오해·주의점**:
  - **"문맥 자유 = 규칙이 자유롭다"**: 오히려 문맥 의존 문법(Type 1)보다 좌변 제약이 더 강하다. "문맥과 무관하게 치환 가능하다"는 뜻이지 "제약이 없다"는 뜻이 아니다.
  - **모호성은 문법의 결함**: 1+2*3이 (1+2)*3인지 1+(2*3)인지 구분 불가한 것은 언어가 아니라 문법 설계의 문제이며, 연산자 우선순위·결합성 규칙으로 제거해야 한다.
  - **좌재귀(Left Recursion)**: A → Aα 형태는 하향식(LL) 파서에서 무한 루프를 유발하므로 우재귀로 변환해야 한다.

## 연결 개념
- **정규 언어·문법 (021)**: 정규 언어는 CFG의 진부분집합(Type 3 ⊂ Type 2)이며, 컴파일러에서 어휘 분석(Lexer)을 담당함.
- **파서 LL·LR (074)**: CFG를 결정론적으로 O(N)에 파싱하는 알고리즘의 상세를 다룸.
- **튜링 머신 (023)**: 촘스키 위계 최상위(Type 0)를 인식하는 완전 계산 모델.
- **컴파일러 구조 (073)**: 어휘 분석→구문 분석→의미 분석 파이프라인에서 CFG의 실무 적용을 다룸.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CFG는 좌변 단일 비단말 기호의 생성 규칙(A → α)으로 정의되는 Type 2 언어로, 푸시다운 오토마타(PDA)가 스택을 활용해 재귀·중첩 구조를 인식함.
> 2. **가치**: 프로그래밍 언어의 구문(Syntax)을 정의하는 표준 모델이며, LL/LR 파서로 O(N) 결정론적 파싱이 가능해 컴파일러 구문 분석의 기반임.
> 3. **판단 포인트**: 문법 모호성 제거(연산자 우선순위·좌인수분해)와 좌재귀 변환이 파서 설계의 핵심이며, 정규 언어(021)와의 역할 분담(Lexer/Parser)이 컴파일러 성능을 좌우함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CFG의 형식 정의와 촘스키 위계 위치 | 4튜플(V, T, P, S), 좌변 단일 비단말 제약, Type 2 | "자유"를 규칙 없음으로 오해 |
| PDA 인식 메커니즘 | 스택 Push/Pop으로 재귀 구조 인식, 결정론적 PDA(DPDA) | 유한 오토마타(FA)와 PDA 혼동 |
| 컴파일러 구문 분석 연결 | AST 생성, LL/LR 파서, BNF 표기법 | 어휘 분석(정규 언어)과 구문 분석(CFG) 혼용 |

> 요약: CFG가 스택(PDA)으로 재귀 구조를 처리하는 원리를 보이고, LL/LR 파서를 통한 컴파일러 구문 분석 파이프라인과 연결해야 함.

## Ⅰ. 개요 및 필요성
- 개요: 좌변에 단일 비단말 기호만 허용하는 생성 규칙 기반의 Type 2 형식 문법으로 재귀·중첩 구조를 정의함
- 배경: 정규 언어(Type 3)는 스택이 없어 a^n b^n(괄호 매칭)·수식 중첩 같은 재귀 구조 표현이 불가능함
- 필요성: 프로그래밍 언어의 구문(블록 중첩·수식 우선순위)을 결정론적으로 파싱하고 AST를 구축하기 위한 문법 모델이 필수임

## Ⅱ. 구조 및 구성요소
선형 구조도 (CFG 4튜플과 인식·파싱 흐름):

    시작 기호(S) -> 생성 규칙(P) 반복 적용 -> 비단말(V) 치환 -> 단말(T) 도달
                                                   |
                                                   +-> 파싱 트리(AST)로 계층화
    인식: 토큰 스트림 -> PDA(스택 Push/Pop) -> Accept/Reject

| 구성요소 | 기호 | 역할 |
|:---|:---|:---|
| 비단말 기호 (Variables) | V | 다른 기호열로 치환 가능한 중간 변수 (예: \<수식\>, \<문장\>) |
| 단말 기호 (Terminals) | T | 더 이상 치환되지 않는 최종 어휘 토큰 (예: if, +, id) |
| 생성 규칙 (Productions) | P | A → α (A ∈ V, α ∈ (V ∪ T)*) 형태의 치환 규칙 |
| 시작 기호 (Start Symbol) | S | 파생이 시작되는 최초 비단말 기호 (S ∈ V) |

> 요약: CFG는 4튜플(V, T, P, S)로 구성되며 생성 규칙의 좌변이 단일 비단말이라는 제약이 "문맥 자유"의 핵심임.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (PDA의 CFG 인식 과정):

    토큰 스트림 입력 -> PDA 시작 상태 -> [열림 기호] 스택 Push -> [닫힘 기호] 스택 Pop·짝 검증 -> 입력 소진+스택 비어 있음 -> Accept

1. 토큰 입력: 어휘 분석기(021·020 참조)가 생성한 토큰 스트림을 순차 입력받음
2. 스택 전이: 입력 토큰과 스택 최상단(Top)을 확인해 Push, Pop 또는 상태 전이를 수행함 — 여는 괄호는 Push, 닫는 괄호는 Pop으로 짝을 매칭함
3. 구문 트리 구축: 하향식(LL)은 시작 기호에서 좌파생, 상향식(LR)은 단말에서 역치환하며 AST를 생성함
4. 수용 판별: 입력 소진 시 스택이 비어 있으면 Accept, 아니면 Reject를 반환하고 유효한 AST를 후속 단계에 전달함

> 요약: PDA가 스택으로 중첩 깊이를 기억하며 토큰을 처리하고, 파서가 생성 규칙 적용 순서를 AST로 구축함.

## Ⅳ. 특징
- 재귀 표현력: A → aAb 같은 자기 참조 규칙으로 무한 깊이의 중첩 구조를 생성 가능함
- 결정론적 파싱 한정: 범용 CFG는 O(N³)(CYK/Earley)이나, 컴파일러는 LL(k)/LR(k) 결정론적 부분집합으로 O(N) 파싱을 달성함
- 모호성 리스크: 동일 문자열에 복수 파싱 트리가 존재하면 해석이 분기하므로, 연산자 우선순위·결합성·좌인수분해로 제거해야 함
- 좌재귀 제약: A → Aα 형태는 LL 파서에서 무한 루프를 유발하므로 우재귀로 변환 필요함

## Ⅴ. 심화 비교 및 적용 판단

촘스키 위계에서 CFG(Type 2)와 인접 클래스의 차이를 대조함. 정규 언어(Type 3)와의 비교 상세는 021 참조.

| 구분 | 정규 언어 (Type 3) | 문맥 자유 언어 (Type 2, CFG) | 문맥 의존 언어 (Type 1) |
|:---|:---|:---|:---|
| 인식 기계 | 유한 오토마타 (FA) | 푸시다운 오토마타 (PDA) | 선형 한계 오토마타 (LBA) |
| 메모리 | 없음 (상태만) | 스택 (LIFO) | 유한 테이프 |
| 표현 한계 | a^n b^n 불가 | a^n b^n c^n 불가 | 범용 계산 불가 |
| 생성 규칙 | A → aB 또는 A → a | A → α (좌변 단일 비단말) | αAβ → αγβ |
| 컴파일러 적용 | 어휘 분석 (Lexer) | 구문 분석 (Parser) | 의미 분석 (심볼 테이블) |

> 요약: 어휘 분석은 정규 언어(FA)로, 구문 분석은 CFG(PDA)로, 의미 분석(변수 스코프 등)은 심볼 테이블로 분리해 각 단계의 복잡도를 최적화함.

**리스크·대응:**
- 문법 모호성: Dangling-Else 같은 모호 구조에서 파싱 트리가 분기 → 연산자 우선순위·결합성 명시 및 좌인수분해(Left Factoring) 적용 (지표: 파싱 트리 유일성)
- 좌재귀 무한 루프: LL 파서에서 A → Aα가 무한 재귀 유발 → 우재귀(A → αA')로 문법 변환 (지표: LL 파싱 에러율 0%)
- 파서 생성기 과신: Yacc/Bison 자동 생성 파서의 Shift-Reduce 충돌을 무시하면 오파싱 발생 → 충돌 0건 확인 후 배포

**점검 지표:**
- 파싱 성능: 소스 코드 100만 줄 파싱 시 O(N) 완료 여부 — LL/LR 파서 벤치마크
- 문법 완전성: 의도한 모든 구문을 생성하고 의도하지 않은 구문은 거부하는지 테스트 스위트로 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 컴파일러 파서 자동화: Yacc/Bison/ANTLR에 CFG를 BNF 표기법으로 입력해 LR(1)/LL(*) 파서를 자동 생성하고 AST를 구축함
2. DSL(도메인 특화 언어) 설계: 사내 비즈니스 룰 엔진·질의어(SQL 변형 등)를 CFG로 정의해 문법 모호성을 사전 차단하고 파서를 자동 생성함
3. 정적 분석 도구: SonarQube·ESLint 등에서 CFG로 생성한 AST를 순회하며 코드 취약점·안티패턴을 탐지함

**결론:**
- 기술사 판단: 정규 언어가 토큰(단어)을 식별한다면 CFG는 구문(문장 구조)을 파악하는 뼈대이므로, 프로그래밍 언어·프로토콜 설계 시 어휘 분석(정규)과 구문 분석(CFG)의 역할 분담이 필수임
- 향후 방향: 에러 복구가 뛰어난 GLL/GLR 파싱, PEG(Parsing Expression Grammar), 그리고 Tree-sitter 같은 점증적(Incremental) 파서가 IDE 실시간 구문 분석의 표준으로 자리잡고 있음
