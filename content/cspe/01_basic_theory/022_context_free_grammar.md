# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 문맥 자유 문법(CFG)은 촘스키 위계 **Type-2 문법**으로, 생성 규칙의 좌변이 항상 비단말 기호 1개로만 이루어져 주변 문맥과 무관하게 치환할 수 있는 문법이다 — 스택 메모리를 가진 푸시다운 오토마타(PDA)와 정확히 대응하며, 정규 언어가 못 하는 중첩·재귀 구조(괄호 짝, 프로그램 블록)를 표현한다.
- **왜 필요한가**: 정규 언어(021 참조)는 개수를 세지 못해 `if(...){ while(...){ } }`처럼 무한히 중첩되는 프로그램 구조를 표현할 수 없다. 스택을 하나 추가해 "지금까지 연 괄호 개수"를 기억할 수 있게 만든 문법이 필요했다.
- **핵심 직관**: `(3 + (2 * 4))`처럼 괄호를 연 만큼 정확히 닫아야 하는 구조를, 양파 껍질처럼 안팎으로 정확히 대응시켜 파악한다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 문맥 자유 문법 (CFG, Type-2) | 생성 규칙 좌변이 비단말 1개로 고정된 문법 — 정규 언어의 상위 계층 | 앞뒤 눈치 안 보고 바로 치환 가능한 규칙집 |
| 비단말 기호 (Non-terminal) | 다른 기호로 더 치환될 수 있는 변수(대문자로 표기) | 아직 완성 안 된 중간 재료 |
| 단말 기호 (Terminal) | 더 이상 치환되지 않는 최종 문자(소문자로 표기) | 완성된 최종 결과물 |
| 생성 규칙 (Production) | "비단말 1개 → 임의의 기호열" 형태의 치환 규칙 | "A를 이걸로 바꿔도 된다"는 레시피 한 줄 |
| 유도 (Derivation) | 시작 기호에서 생성 규칙을 반복 적용해 최종 문자열을 만들어가는 과정 | 레시피를 순서대로 따라가며 요리를 완성 |
| 파스 트리 (Parse Tree) | 유도 과정을 트리로 시각화한 것 — 루트가 시작 기호, 리프가 최종 문자열 | 요리 과정을 계통도로 그린 것 |
| 모호성 (Ambiguity) | 같은 문자열에 대해 서로 다른 파스 트리가 2개 이상 존재하는 문법의 결함 | 같은 대본을 두 가지로 다르게 해석 가능한 상태 |
| 좌측 재귀 (Left Recursion) | 규칙 좌변이 자기 자신으로 다시 시작하는 규칙(예: A→Aα) — 하향식(LL) 파서를 무한 루프에 빠뜨림 | 첫 문장을 자기 자신으로 다시 시작하는 순환 정의 |
| 촘스키 정규형 (CNF) | 모든 규칙을 "비단말 2개" 또는 "단말 1개" 형태로 표준화한 CFG — CYK 알고리즘의 전제 조건 | 모든 레시피를 "재료 2개 조합" 또는 "완제품 1개"로 통일한 표준 양식 |
| 푸시다운 오토마타 (PDA) | 유한 오토마타에 LIFO 스택 1개를 추가한 기계 — CFG를 인식하는 짝 모델 | 되돌아갈 길을 스택에 적어두는 미로 탐험가 |

## 깊이 이해

### 왜 좌변을 비단말 1개로 제한하면 "문맥 자유"가 되는가
- 정규 문법은 우변 형태를 제약했지만(021 참조), CFG는 좌변 형태를 제약한다: 좌변이 항상 단일 비단말 A뿐이라, "A 앞뒤에 무엇이 와도" A를 보면 무조건 규칙을 적용해 치환할 수 있다. 이것이 "문맥(주변 상황)을 따지지 않는다(Context-Free)"는 이름의 유래다.
- 대조로 문맥 의존 문법(Type-1)은 A 양옆에 특정 문맥이 있어야만 치환이 허용된다 — 훨씬 강력하지만 파싱이 비효율적이라 실용 컴파일러에서는 거의 쓰지 않는다.

### a를 n개, b를 n개 이어붙인 언어를 CFG로 정확히 생성하는 예제
- 규칙: S → aSb, S → ε(빈 문자열). 유도 과정: S ⇒ aSb ⇒ a(aSb)b ⇒ aa(ε)bb ⇒ aabb.
- 이 유도를 PDA로 실행하면 a를 읽을 때마다 스택에 push, b를 읽을 때마다 pop한다. 입력이 끝났을 때 스택이 정확히 비어있으면 accept한다. "a의 개수만큼 b의 개수를 정확히 맞춰야 한다"는 카운팅을, 정규 언어는 못 하지만 CFG와 PDA는 스택 덕분에 해낸다.

### 모호성이 왜 치명적인가 — 3+4*5 예제로 확인
- 모호한 문법(덧셈과 곱셈을 구분 없이 한 규칙으로 처리)으로 "3+4*5"를 파싱하면 두 가지 파스 트리가 나온다 — (3+4)*5=35로 묶는 트리와 3+(4*5)=23으로 묶는 트리. 컴파일러가 어느 트리를 쓸지 결정할 수 없으면 같은 코드가 실행마다 다른 값을 낼 수 있다.
- 해결: 연산자 우선순위를 문법 계층으로 하드코딩한다. 곱셈을 표현하는 비단말을 덧셈을 표현하는 비단말보다 문법 트리의 더 아래(먼저 묶이는 위치)에 두면, 모호성이 사라지고 파스 트리가 유일하게 결정된다.
- 임의의 CFG가 모호한지 판별하는 일반 알고리즘은 존재하지 않는다(결정 불가능). 그래서 실무에서는 처음부터 모호하지 않은 문법을 설계하거나, LL(1)·LR(1) 같은 결정적 파서 클래스로 제한해 문법 생성 시점에 충돌(Shift-Reduce, Reduce-Reduce)을 검출한다.

### 좌측 재귀와 파서 선택의 관계
- 좌측 재귀 규칙(예: S→Sa, S→b)을 하향식(Top-down, LL) 파서로 그대로 파싱하면, S를 만날 때마다 다시 S를 전개하려 해 입력을 한 글자도 소비하지 못한 채 무한 재귀에 빠진다.
- 우측 재귀로 변환(예: S→bS', S'→aS', S'→ε)하면 같은 언어(b 다음에 a가 0개 이상)를 생성하면서도 무한 루프를 피한다. 반면 상향식(Bottom-up, LR) 파서는 좌측 재귀를 자연스럽게 처리할 수 있어 이 변환이 필요 없다 — 이것이 Yacc·Bison이 LALR(상향식)을 채택하는 이유 중 하나다.

### 비유
- 러시아 인형 마트료시카처럼, 인형 안에 더 작은 인형을 넣고 그 안에 또 넣는 식으로 끝없이 재귀적으로 파고들 수 있는 구조를 CFG가 표현한다. 정규 언어는 인형을 한 줄로만 세울 수 있을 뿐, 안에 넣는(중첩) 것은 못 한다.

## 연결 개념
- 정규 언어 — CFG의 하위 계층(카운팅·중첩 불가) (021 참조)
- 푸시다운 오토마타(PDA) — CFG를 인식하는 짝꿍 기계
- 튜링 머신 — CFG보다 상위인 문맥 의존 문법(Type-1)을 넘어서는 최상위 계산 모델 (023 참조)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 촘스키 위계 Type-2에 해당하는 문법으로, 생성 규칙의 좌변이 항상 단일 비단말 기호 1개로만 구성되어 치환 시 주변 문맥(Context)을 고려하지 않는 구문 구조다.
> 2. **가치**: LIFO 스택 구조를 통해 재귀적 중첩(`a^n b^n`, 괄호 매칭 등)을 100% 수학적으로 검증할 수 있어, 세상 모든 프로그래밍 언어의 AST(추상 구문 트리)를 생성하는 파서(Parser)의 토대가 된다.
> 3. **판단 포인트**: CFG 설계 시 모호성(Ambiguity)이 방치되면 파싱 트리가 여러 개 도출되어 컴파일러 에러를 유발하므로, 연산자 우선순위와 결합 법칙을 강제하여 모호성을 원천 제거해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 문법(Type-3) 한계 극복 원리 구조 | 단일 비단말 좌변($A$)과 제한 없는 우변 유도 규칙 | '문맥 자유' 용어를 '아무 제약이 없음'으로 오독 서술 |
| 컴파일러 구문 분석(Syntax Analysis) 맵핑 | 파스트리(Parse Tree) 생성, 좌/우측 유도(Derivation) 과정 | 구문 분석과 하위 어휘 분석(Lexer)의 역할 혼용 기술 |

> 요약: CFG는 프로그래밍 언어의 문법(IF, WHILE 중첩)을 트리 구조로 파싱하기 위해, 생성 규칙 우변의 제약을 완화하여 재귀적 가지치기를 허용한 수학적 마스터키다.

## Ⅰ. 개요 및 필요성

- 정의: 푸시다운 오토마타(PDA)로 인식 가능하며, 생성 규칙 좌변에 단 하나의 비단말 기호만 존재하는 촘스키 Type-2 문법 체계
- 배경: 정규 언어는 메모리 부재로 인해 괄호 쌍 맞추기, 함수 호출 중첩 등 프로그래밍 문법의 재귀적 구조 해석 불가능 한계 직면
- 필요성: BNF 표기법을 통해 컴파일러가 소스 코드 구문의 무결성을 수학적으로 파싱하고 추상 구문 트리(AST)를 완벽히 구축하기 위해 필수

## Ⅱ. 구성요소 및 문맥 자유 생성 규칙

```text
Type 1: 문맥 의존 언어 (선형 한계 오토마타) ⊃ Type 2: 문맥 자유 언어 (PDA) ⊃ Type 3: 정규 언어 (DFA)
```

| 기호 (4튜플 $G = (V, T, S, P)$) | 역할 및 의미 | 실무 제약 사항 (정규 문법과 비교) |
|:---|:---|:---|
| $V$ (비단말 기호) | 문법 구조를 나타내는 변수 (대문자 표기) | 상태 치환 가능 객체 |
| $T$ (단말 기호) | 더 쪼개지지 않는 텍스트 문자열 (토큰) | 리프 노드 출력 값 |
| $S$ (시작 기호) | 파생을 시작하는 단일 루트 비단말 기호 | $S \in V$ |
| **$P$ (생성 규칙)** | $A \rightarrow \gamma$ ($\gamma \in (V \cup T)^*$) 치환 규칙 | **좌변은 무조건 비단말 1개**, 우변은 자유로운 재귀 허용 |

> 요약: 좌변에 비단말이 1개라는 것은, $A$ 앞뒤 기호 유무에 상관없이(Context-Free) 독립적으로 $\gamma$ 치환 연산을 병렬 전개할 수 있다는 뜻이다.

## Ⅲ. 유도(Derivation) 원리 및 파스 트리 흐름도

```text
[최좌단 유도 (Leftmost Derivation) 예시: 규칙 $S \rightarrow aSb \; | \; \epsilon$]
$S$ -> $aSb$ -> $a(aSb)b$ -> $aa(\epsilon)bb$ -> $aabb$ (문자열 수용 완료, $a^n b^n$ 동기화 매칭)
```

| 동작 메커니즘 | 처리 내용 | 검증 기준 (특징) |
|:---:|:---|:---|
| 푸시다운 연동 | $a$가 들어오면 스택에 Push, $b$가 들어오면 Pop | 스택이 완벽히 비워지고 입력이 끝나면 Accept |
| 최좌단/최우단 유도 | 치환할 비단말을 고를 때 항상 가장 왼쪽(또는 오른쪽) 선택 | 파서(Top-down LL, Bottom-up LR) 아키텍처 설계 기준 |
| 파스 트리 구축 | 유도 과정을 역으로 그려 $S$를 루트 노드로 하는 구문 트리 생성 | 모호성(Ambiguity)이 1개라도 발생하면 구문 에러 붕괴 |

> 요약: CFG는 우변 제약이 풀려있기 때문에 $S$가 $aSb$처럼 양옆으로 동시에 성장하는 재귀 트리를 생성하며, 이는 스택 메모리 점유를 100% 활용한다.

## Ⅴ. 심화 비교 판단 (CFG 모호성 한계 및 제거 방안)

| 구분 | 모호한 문법 (Ambiguous Grammar) | 모호하지 않은 문법 (Unambiguous) | 컴파일러 판단 기준 |
|:---|:---|:---|:---|
| 정의 | 단일 문자열에 대해 2개 이상의 상이한 파스 트리 생성 | 유일한 파스 트리 1개만 생성 도출 보장 | AST 렌더링 노드 충돌 검증 |
| 한계/장애 사례 | `3 + 4 * 5` 입력 시 덧셈/곱셈 중 어떤 묶음을 먼저 할지 미정 | 곱셈 비단말 기호를 트리의 더 하단(우선순위 높음)에 강제 배치 | 결과값 오동작(23 vs 35) 원천 차단 |
| 해결 정규화 방안 | 연산자 우선순위 및 결합 법칙을 생성 규칙 분할로 직접 하드코딩 | | 촘스키 정규형(CNF) 변환 치환 |

> 요약: CFG에 모호한 뼈대를 넣으면 컴파일러가 코드를 랜덤하게 쪼갤 수 있으므로(Dangling Else 문제), 문법 설계자가 우선순위 족쇄 규칙을 추가해야 한다.

| 리스크 | 발생 원인 | 대응 기법 (최적화) | 확인 지표 |
|:---|:---|:---|:---|
| 무한 좌측 재귀 폭발 | $A \rightarrow A\alpha$ 형태 규칙 존재 시 Top-down 파서(LL)가 좌측 파고들기 무한 루프 빠짐 | 좌측 재귀를 우측 재귀 형태($A \rightarrow \beta A'$)로 변환하는 수학적 치환 튜닝 수행 | 파서 Call Stack Depth 오버플로우 |
| 모호성 판별 불가능 | 임의의 CFG가 모호한지 여부를 판정하는 일반 알고리즘은 수학적으로 존재하지 않음(Undecidable) | LL(1)/LR(1) 등 결정적 하위 클래스로 문법을 제한해 파서 생성 시점에 충돌 검출 | Yacc/Bison 빌드 로그의 Shift-Reduce·Reduce-Reduce 충돌 건수 |

> 요약: 좌측 재귀와 모호성은 문법 설계 단계에서 방치하면 파서 생성 실패 또는 무한 루프로 직결되므로, 문법 변환·문법 클래스 제한으로 사전 차단해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 구문 분석기(Parser): Bison/Yacc 프레임워크에 타겟 언어의 CFG(BNF 표기법)를 입력하면, Lexer가 넘긴 토큰 스트림을 읽어 LALR 바텀업 파싱으로 AST(추상 구문 트리) 자동 렌더링
2. 마크업 언어(XML, HTML5) DOM 파싱: 브라우저 렌더링 엔진(Blink)이 중첩 닫기 태그(`<div><span></span></div>`) 위반 여부를 검증하고 DOM 트리를 구축할 때 CFG 푸시다운 연산 적용
3. 자연어 처리(NLP) 통계적 구문 분석: 문장을 명사구(NP)와 동사구(VP)로 분해하는 구문 트리 생성 시, PCFG(Probabilistic CFG)를 적용하여 모호한 가지치기 중 확률이 가장 높은 파스트리 채택

**결론 (2줄):**
- 기술사 판단: 문맥 자유 문법은 정규 언어의 기억 한계를 LIFO 스택으로 돌파하여 중첩 구조를 표현하는, 세상 모든 프로그래밍 언어의 뼈대이자 파서의 심장이다.
- 향후 방향: 최근 프로그래밍 언어 설계에서는 LLVM 프레임워크 기반 프런트엔드에서 CFG 모호성을 강력히 통제하고, AST 변환 속도를 극대화하는 방향으로 최적화되고 있다.
