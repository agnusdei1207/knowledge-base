## Ⅰ. 개요
- **정의**: 생성 규칙 `A -> α`로 언어를 정의하고 푸시다운 오토마타(PDA)로 인식하는 문법 체계
- **배경/필요성**: 정규 언어(021 참조)로 표현 불가능한 중첩 구조(괄호, 블록)를 기술할 수학적 도구가 필요함
- **비유**: 러시아 인형(마트료시카)처럼 구조 안에 같은 구조가 재귀적으로 들어가는 규칙

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CFG 4-튜플 구성 이해 | `G = (V, T, P, S)` 각 요소 설명 | 비단말 집합 V와 단말 집합 T의 교집합은 공집합 |
| PDA와의 대응 | CFG가 생성하는 언어 = PDA가 인식하는 언어 | 결정적 PDA(DPDA)는 CFG 전체가 아닌 부분집합만 인식 |
| 모호성과 정규형 | 파스 트리가 2개 이상이면 모호한 문법 | CNF/GNF 변환이 모호성 자체를 제거하지는 않음 |

> 요약: 재귀적 생성 규칙으로 중첩 구조를 표현하며, PDA가 이를 인식함

## Ⅱ. 구성요소
```text
  G = (V, T, P, S)
        |
        v
  +----------+     +----------+
  | 비단말 V  |     | 단말 T   |
  +----+-----+     +----+-----+
       |                |
       v                v
  +----+----------------+-----+
  |   생성 규칙 P: A -> α     |
  +----+-----------------------+
       |
       v
  +----+-----+
  | 시작 기호 S|
  +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 비단말 기호(V) | 생성 규칙의 좌변에 올 수 있는 변수 기호 집합 | 문장에서 '주어', '서술어' 같은 문법 범주 |
| 단말 기호(T) | 최종 문자열을 구성하는 알파벳 기호 집합 | 실제로 출력되는 글자 |
| 생성 규칙(P) | `A -> α` 형태로 비단말을 단말·비단말 조합으로 치환하는 규칙 | 요리 레시피의 단계별 지시 |
| 시작 기호(S) | 유도(derivation)의 출발점이 되는 비단말 기호 | 책의 첫 페이지 |
| 파스 트리 | 유도 과정을 트리 구조로 시각화한 것 | 가계도 — 조상에서 후손으로 분기 |
| PDA | 스택을 보조 메모리로 사용하여 CFG 언어를 인식하는 오토마타 | 접시 쌓기 — 마지막에 넣은 것을 먼저 꺼냄 |

> 요약: 4-튜플 문법 정의와 PDA 인식기, 파스 트리가 핵심 구성임

## Ⅲ. 절차
```text
  문법 정의 --> 정규형 변환 --> 파싱 --> 파스 트리 생성
```
- 1단계: 대상 언어의 구문 구조를 생성 규칙 `A -> α`로 정의함
- 2단계: CNF(촘스키 정규형) 또는 GNF(그라이바흐 정규형)로 변환하여 파싱 알고리즘 적용 가능 형태로 정리함
- 3단계: CYK(CNF 기반, `O(n^3)`) 또는 Earley 파서로 입력 문자열의 유도 가능 여부를 판별함
- 4단계: 유도 과정을 파스 트리로 구성하여 구문 구조를 확정함(컴파일러 적용은 073/074 참조)

> 요약: 문법 정의 → 정규형 변환 → 파싱 → 파스 트리 순으로 구문 분석을 수행함

## Ⅳ. 문제점
- 모호성(Ambiguity): 하나의 문자열에 파스 트리가 2개 이상 존재 — 의미 해석이 비결정적이 됨
- 파싱 성능: 범용 파서(CYK)의 시간 복잡도가 `O(n^3)` — 대규모 입력에서 처리 시간이 급증함
- 표현력 한계: 교차 의존(`a^n b^n c^n`) 등 문맥 의존 구조를 생성 불가 — 자연어·일부 프로그래밍 제약 표현에 부족함

> 요약: 모호성, 파싱 비용, 문맥 의존 구조 표현 불가가 주요 한계임

## Ⅴ. 개선방안
1. 단기: 연산자 우선순위·결합 규칙을 명시하여 모호성을 제거한 비모호 문법으로 재설계
2. 중기: LL/LR 등 결정적 파싱 기법을 적용하여 `O(n)` 시간 복잡도로 파싱 성능 확보(073/074 참조)
3. 장기: 문맥 의존 문법(CSG, 023 참조)이나 속성 문법(Attribute Grammar)으로 확장하여 표현력 보완

> 요약: 문법 재설계, 결정적 파싱, 상위 문법 확장으로 각 한계를 대응함

## Ⅵ. 전망
- 발전 방향: DSL(도메인 특화 언어) 설계, 프로토콜 명세 등에서 CFG 기반 파서 생성기 활용 확대
- 기술사적 판단: CFG는 프로그래밍 언어 구문 정의의 표준 도구이며, 컴파일러 프론트엔드의 핵심 기반임
- 기술사 제언: 정규 언어(021 참조)와 문맥 의존 언어(023 참조) 사이에서 문제 복잡도에 맞는 문법 클래스를 선택하는 판단력 필요
