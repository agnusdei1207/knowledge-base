# 022. 문맥 자유 문법 (Context-Free Grammar)

## 미리 알고가기

- **단말 기호 (Terminals)**: 문법에서 더 이상 분해되지 않는 실제 입력 기호들임 (예: `if`, `+`, `number`)
- **비단말 기호 (Non-terminals)**: 다른 기호들의 나열로 치환될 수 있는 추상적 범주임 (예: `<expression>`, `<statement>`)
- **파스 트리 (Parse Tree)**: 문법 규칙에 따라 문자열이 생성되는 과정을 계층적 트리 구조로 나타낸 것임

## Ⅰ. 개요

- **정의/개념**: 문맥 자유 문법(Context-Free Grammar, CFG)은 생성 규칙의 좌변에 오직 하나의 비단말 기호만 올 수 있는 형식 문법으로, 촘스키 계층의 Type 2에 해당하며 푸시다운 오토마타(PDA)에 의해 인식됨
- **배경/필요성**: 정규 문법은 유한 상태만 기억할 수 있어 괄호의 짝 맞추기나 블록 구조와 같은 '중첩(Nesting)'을 표현하지 못함. 프로그래밍 언어의 복잡한 구문 구조(Syntax)를 정의하고, 이를 기계적으로 해석할 수 있는 구문 분석기(Parser)를 설계하기 위해 사용함

## Ⅱ. 특징 및 비교

CFG는 정규 문법보다 표현력이 강하며, 문맥 의존 문법보다는 제약이 많아 효율적인 파싱 알고리즘 설계가 가능함.

| 비교 항목 | 정규 문법 (Type 3) | 문맥 자유 문법 (Type 2) | 문맥 의존 문법 (Type 1) |
|:---|:---|:---|:---|
| **기억 장치** | 없음 (유한 상태) | **스택 (Stack)** | 선형 한계 테이프 |
| **인식 기계** | 유한 오토마타 (FA) | **푸시다운 오토마타 (PDA)** | 선형 유한 오토마타 (LBA) |
| **생성 규칙** | $A \rightarrow aB, A \rightarrow a$ | **$A \rightarrow \alpha$ ($\alpha$는 기호의 나열)** | $\alpha A \beta \rightarrow \alpha \gamma \beta$ |
| **표현 대상** | 단순 패턴, 토큰 | **프로그래밍 언어 구문, 괄호** | 자연어의 복잡한 제약 |
| **주요 용도** | 어휘 분석 (Lexer) | **구문 분석 (Parser)** | 고급 언어 분석 |

> 요약: 스택이라는 '메모리'를 통해 여는 괄호만큼 닫는 괄호가 나오는지 세는 능력을 갖춘 것이 CFG의 본질임.

## Ⅲ. 구성요소/구조

CFG는 4-튜플($G = (V, \Sigma, P, S)$)로 정의되며, 주로 BNF(Backus-Naur Form) 표기법을 사용하여 기술됨.

- **구성요소**:
  - $V$: 비단말 기호들의 유한 집합
  - $\Sigma$: 단말 기호들의 유한 집합 (알파벳)
  - $P$: 생성 규칙들의 유한 집합 (치환 규칙)
  - $S$: 시작 비단말 기호 ($S \in V$)

- **유도(Derivation) 및 트리 구조 (원리/흐름도)**:

```text
[Grammar Rule]    [Derivation Process]         [Parse Tree]
E -> E + T | T      E => E + T                      E
T -> id                => T + T                   / | \
                       => id + T                 E  +  T
                       => id + id                |     |
                                                 T     id
                                                 |
                                                 id
```

1. **좌측 유도 / 우측 유도**: 가장 왼쪽 또는 오른쪽 비단말 기호부터 치환해 나가는 방식
2. **중첩 구조 표현**: $S \rightarrow (S) | \epsilon$ 과 같은 재귀적 규칙을 통해 무한한 깊이의 중첩을 표현함

## Ⅳ. 문제점 및 개선방안

1. **모호성 (Ambiguity)**: 동일한 문자열에 대해 서로 다른 파스 트리가 생성되어 해석의 결과가 달라지는 현상 (예: 사칙연산의 우선순위 미지정 시)
   - **개선방안**: 연산자 우선순위와 결합 법칙을 생성 규칙에 명시적으로 반영하여 문법을 재작성하거나, 파싱 시 우선순위 규칙을 별도로 부여함 (확인: 고유한 파스 트리 생성 여부)

2. **좌재귀 (Left Recursion)**: $A \rightarrow A\alpha$ 와 같이 규칙의 시작이 자신인 경우, 하향식 파서(LL Parser)가 무한 루프에 빠짐
   - **개선방안**: 좌재귀를 우재귀($A \rightarrow \beta A', A' \rightarrow \alpha A' | \epsilon$)로 변환하거나, 상향식 파서(LR Parser)를 사용하여 해결함 (확인: 파싱 알고리즘과의 호환성)

3. **비효율적 파싱 복잡도**: 일반적인 CFG의 파싱은 $O(n^3)$의 시간이 걸릴 수 있어 실시간 처리에 부담이 됨
   - **개선방안**: 프로그래밍 언어 설계 시 선형 시간($O(n)$)에 파싱이 가능한 특수 부분 집합인 **LL(k)** 또는 **LR(k)** 문법을 사용하여 최적화함 (확인: 파싱 복잡도 지표)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 프로그래밍 언어 명세 | C, Java, Python 등 언어의 전체 구문 구조를 BNF 또는 EBNF로 기술 | 문법의 명확성, 확장 가능성 |
| 구문 분석기 생성 (Yacc/Bison) | CFG를 입력으로 받아 실행 가능한 C/Java 파서 코드를 자동으로 생성 | 생성된 코드의 속도, 오류 복구 능력 |
| 데이터 교환 포맷 (JSON/XML) | 중첩된 객체와 리스트의 구조가 유효한지 CFG 기반의 스키마 검증 수행 | 데이터 무결성, 파싱 지연 시간 |
| 도메인 특화 언어 (DSL) | 특정 업무 로직을 표현하기 위한 전용 언어의 문법을 정의하고 해석 | 사용자 가독성, 로직 해석 정확도 |

> 요약: 프로그래밍 언어의 뼈대를 설계하고 이를 컴퓨터가 이해하게 만드는 구문 해석의 핵심 표준임.

## Ⅵ. 결론

문맥 자유 문법은 텍스트의 '나열'을 의미 있는 '구조'로 전환하는 연결 고리임. 기술사는 정규 언어의 한계를 극복하기 위해 왜 스택 기반의 CFG가 필요한지 이해하고, 실제 파서 구현 시 직면하게 되는 모호성과 좌재귀 문제를 해결할 수 있는 설계 능력을 갖추어야 함.

특히 현대 소프트웨어 아키텍처에서는 단순한 컴파일러 제작을 넘어, 설정 파일 검증이나 사용자 정의 쿼리 해석 등 다양한 영역에서 CFG 기반의 파싱 기술이 요구됨. 결국 CFG는 복잡한 데이터의 계층적 구조를 정형화하여 시스템의 안정성과 유연성을 동시에 확보하는 구문 설계의 정석임.
