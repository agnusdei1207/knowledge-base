## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 생성 규칙의 좌변이 단일 비단말 기호로 구성되어 주변 문맥과 무관하게 치환 가능한 형식 문법임 |
| 배경/필요성 | 프로그래밍 언어의 구문(Syntax)을 정의하고, 괄호 매칭 등 중첩 구조를 표현하기 위해 필요함 |
| 출제 의도 | 구문 분석 트리(Parse Tree) 생성 원리와 푸시다운 오토마타(PDA)와의 관계 이해도 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|   Non-terminal    | ----> |     Terminal      | ----> | Production Rules  |
|   (Variables)     |       |     (Symbols)     |       | (A -> α)          |
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 비단말 기호 | 다른 기호열로 치환될 수 있는 추상적인 구문 범주 (예: S, A) | 문장 성분(주어, 동사) |
| 단말 기호 | 더 이상 치환되지 않는 최종 문자 또는 식별자 | 실제 단어 |
| 생성 규칙 | A -> α 형태로, 좌변의 비단말 기호를 우변의 기호열로 대체하는 규칙 | 문법 치환 공식 |
> 요약: 문맥 자유 문법은 비단말 기호, 단말 기호, 생성 규칙, 시작 기호의 4튜플(V, T, P, S)로 구성됨

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 문법 정의   | -> | 2. 입력열 스캔 | -> | 3. 파싱 수행   | -> | 4. 트리 생성   |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 문법 정의: 언어의 구문 구조를 문맥 자유 문법(BNF 표기법 등)으로 명세함
2. 입력열 스캔: 어휘 분석기를 통해 입력 문자열을 토큰(Token)의 열로 변환함
3. 파싱 수행: 하향식(Top-down) 또는 상향식(Bottom-up) 파서를 사용하여 생성 규칙을 적용함
4. 트리 생성: 적용된 규칙에 따라 구문 분석 트리(Parse Tree)를 구축하여 구조적 유효성을 검증함
> 요약: 정의된 문법에 따라 입력열을 분석하고, 구문 트리를 생성하여 언어의 계층적 구조를 해석함

## Ⅳ. 문제점
- 모호성 발생: 동일한 입력 문자열에 대해 두 개 이상의 서로 다른 구문 분석 트리가 생성될 수 있음
- 문맥 제약 불가: 변수의 선언 여부 확인이나 타입 일치 등 '문맥 의존적' 의미 제약을 표현할 수 없음

## Ⅴ. 개선방안
- 모호성 제거 규칙 도입: 연산자 우선순위 및 결합법칙을 명시하거나, 문법을 재작성하여 모호성을 해결함
- 속성 문법 및 기호 표 활용: 의미 분석 단계를 추가하고 기호 표(Symbol Table)를 연동하여 문맥 의존 제약을 검증함

## Ⅵ. 전망
- 문맥 자유 문법은 컴파일러의 핵심 이론으로 확고히 자리 잡았으며, 향후 자연어 처리의 초기 구문 분석 및 도메인 특화 언어(DSL) 설계 도구와 융합되어 활용도가 지속될 것임
