## Ⅰ. 개요

- **정의**: 문맥 자유 문법(Context-Free Grammar, CFG)은 생성 규칙의 좌변이 단일 비단말 기호 하나($A \to \alpha$)로만 구성되어, 주변 문맥과 무관하게 동일 규칙으로 치환 가능한 촘스키 Type 2 형식 문법임.
- **배경/필요성**: 정규 언어(021)는 유한 오토마타로 인식되어 상태 기억만으로 판별 가능하지만, 중첩 괄호·if-else 중첩 같은 재귀 구조는 "지금까지 몇 겹 들어갔는지"를 세야 하므로 상태 수만으로 표현 불가능함. CFG는 좌변이 하나뿐인 재귀적 치환 규칙을 허용해 이 재귀 구조를 정의함.
- **출제 의도**: 생성 규칙 형식과 유도(Derivation) 과정의 이해, 파스 트리 구성 능력, 모호성(Ambiguity) 판별·해소 방법, BNF 기반 파서 설계 실무력을 확인함.
- **답안 방향**: 구조(4-튜플·생성 규칙) -> 동작(좌측 유도·파스 트리) -> 특징(모호성·파싱 복잡도) -> 비교(LL/LR 선택 기준) -> 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생성 규칙과 파스 트리 유도 과정 설명 요구 | 생성 규칙 형태($A \to \alpha$), 좌측 유도 순서, 모호 문법 판별·해소 방법 | 정규 언어와 혼동, 모호성 언급 누락, 파스 트리 없이 설명 |

> 요약: CFG 답안은 좌변 단일 비단말 규칙의 재귀성을 먼저 못 박고, 유도·파스 트리·모호성 판정을 순서대로 짚어야 함.

## Ⅱ. 구조 및 구성요소

```text
G = (V, Σ, R, S)
V = {S, E, T, F}          -- 비단말 기호 집합
Σ = {+, *, (, ), id}      -- 단말 기호 집합
R = { E -> E + T | T,     -- 생성 규칙 집합(좌변은 항상 단일 비단말)
      T -> T * F | F,
      F -> ( E ) | id }
S = E                     -- 시작 기호
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 비단말 기호(V) | 파생 중간 단계의 추상 범주, 규칙에 의해 다른 기호열로 치환됨 | 조립 설명서의 서브 어셈블리 |
| 단말 기호(Σ) | 더는 치환되지 않는 최종 토큰 | 레고 낱개 블록 |
| 생성 규칙(R) | $A \to \alpha$ 형태로 좌변 비단말 하나를 우변 기호열로 치환 | 조립 설명서 각 단계 |
| 시작 기호(S) | 모든 유도가 출발하는 특수 비단말 | 완성품 이름표 |
| 파스 트리 | 유도 과정을 트리로 시각화, 루트=S·내부노드=비단말·리프=단말 | 유도 과정의 가계도 |

> 요약: R의 좌변이 단일 비단말로 고정된다는 점이 '문맥 자유'의 근거이며, 파스 트리는 R 적용 순서를 기록한 결과물임.

## Ⅲ. 동작원리 및 흐름도

```text
시작 기호 S 지정 -> 좌측 최선단 비단말 선택 -> 적용 가능 규칙으로 치환 -> 단말만 남으면 종료
                                                    |
                                                    +-> 비단말이 남으면 위 과정 반복
```

- 1단계(시작 기호 지정): 유도(Derivation)는 항상 시작 기호 $S$에서 출발함.
- 2단계(좌측 유도 선택): 현재 문자열에서 가장 왼쪽 비단말 기호를 다음 치환 대상으로 선택함(좌측 유도 기준).
- 3단계(규칙 적용·반복): 선택된 비단말에 적용 가능한 생성 규칙 하나로 치환하고, 비단말이 남아 있으면 2단계로 돌아감.
- 4단계(종료·파스 트리 완성): 문자열이 단말 기호로만 구성되면 유도 종료, 치환 이력을 트리로 그리면 파스 트리가 완성됨.

```text
[유도 예시: id + id * id, 문법은 Ⅱ와 동일]
E => E + T => T + T => F + T => id + T => id + T * F => id + F * F => id + id * F => id + id * id

[결과 파스 트리]
E
+-- E
|   +-- T
|       +-- F
|           +-- id
+-- +
+-- T
    +-- T
    |   +-- F
    |       +-- id
    +-- *
    +-- F
        +-- id
```

> 요약: 좌측 유도를 반복 적용해 단말 문자열에 도달하는 과정이 곧 파스 트리를 아래에서 위로 완성하는 과정임.

## Ⅳ. 특징

- 표현력: 좌변 단일 비단말의 재귀적 자기 참조 규칙(예: $E \to E + T$)으로 정규 언어가 표현 못하는 중첩·재귀 구조(괄호 짝, if-else 중첩)를 생성함.
- 모호성(Ambiguity): 동일 문자열에 대해 서로 다른 파스 트리가 존재할 수 있는 문법 특성. `if a then if b then s1 else s2`에서 `else`가 어느 `if`에 대응하는지 생성 규칙만으로 결정되지 않는 dangling-else 문제가 대표 사례임. 연산자 우선순위·결합 규칙을 문법 구조에 내장하거나 여문법(disambiguating rule)을 추가해 해소함.
- 파싱 복잡도: 임의의 CFG는 촘스키 정규형(CNF) 변환 후 CYK 알고리즘으로 $O(N^3)$에 파싱되나, 모호성 없는 결정론적 서브셋(LL/LR 문법)은 $O(N)$ 선형 시간 파싱이 보장됨.
- 닫힘 성질 한계: 합집합·연접·클리니 스타에는 닫히나, 교집합·여집합에는 닫히지 않아 두 CFG의 교집합이 CFG가 아닐 수 있음.

> 요약: CFG의 재귀 표현력은 모호성 가능성과 $O(N^3)$ 파싱 비용을 대가로 하며, 실무는 결정론적 서브셋으로 제한해 $O(N)$을 확보함.

## Ⅴ. 심화 비교 및 적용 판단

| 판단 기준 | LL 파서(Top-down) | LR 파서(Bottom-up) | 선택 기준 |
|:---|:---|:---|:---|
| 파싱 방향 | 좌측 유도, 예측(Predict) 방식 | 우측 유도 역순, 이동-축약(Shift-Reduce) 방식 | 예측 가능한 문법이면 LL, 좌재귀 문법이면 LR |
| 좌재귀 처리 | 직접 처리 불가, 문법 변환 필요 | 자연스럽게 처리 가능 | 산술식처럼 좌재귀가 흔한 문법은 LR |
| 구현 방식 | 재귀 하강 파서로 수동 구현 용이 | 파서 테이블 생성기(Yacc·Bison) 필요 | 도구 도입 여력이 없으면 LL 수동 구현 |
| 대표 도구 | ANTLR, 수동 재귀 하강 | Yacc, Bison | 문법 규모·유지보수 인력에 따라 선택 |

> 요약: LL은 구현이 직관적이나 좌재귀에 약하고, LR은 좌재귀·표현 범위가 넓으나 파서 생성기 의존도가 높아, 문법 특성과 도구 여건으로 선택함.

- 임의의(모호성 포함) CFG를 다뤄야 하는 자연어 처리·문법 검증 영역은 LL/LR 대신 CYK 알고리즘으로 CNF 변환 후 전수 파싱해 모든 파스 트리 후보를 확인함.

**리스크·대응 (불릿):**
- 모호 문법 방치: dangling-else 등 우선순위·결합 규칙 미정의가 원인 → 문법 재작성 또는 명시적 결합 규칙 추가로 대응함(지표: 파스 트리 유일성 회귀 테스트 통과율).
- 파서 폭탄(Parser Bomb): 외부 입력에 악의적으로 깊은 중첩 구조를 주입하는 것이 원인 → 파싱 깊이 제한(Depth Limit) 설정으로 대응함(지표: 최대 중첩 허용치 초과 요청 차단 건수).

**도입 후 점검 지표 (불릿):**
- 파싱 성능: 결정론적 문법의 실측 파싱 시간이 입력 길이에 선형($O(N)$)으로 증가하는지 확인함.
- 모호성 검증: 문법 변경 시 동일 입력에 대한 파스 트리 유일성 회귀 테스트로 확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 언어의 구문을 BNF/EBNF로 명세화하고 dangling-else류 모호성 존재 여부를 점검함.
2. 중기: ANTLR·Yacc·Bison 등 파서 생성기로 LL/LR 파서를 자동 생성하고, 우선순위·결합 규칙을 문법에 반영해 모호성을 해소함.
3. 장기: 파싱 깊이 제한과 파스 트리 유일성 회귀 테스트를 CI 파이프라인에 통합해 문법 변경의 안전성을 지속 관리함.

- 기술사적 판단: 결정론적 CFG 범위 내에서 설계 가능하면 LL/LR로 $O(N)$ 파싱을 우선 확보하고, 임의 CFG가 불가피하면 CYK로 검증 후 채택함.
- 기술사 제언: 모호성 해소를 파서 생성기 도입 이후가 아니라 문법 설계 단계에 내장해, 생성기 의존으로 인한 은닉 리스크를 줄여야 함.
