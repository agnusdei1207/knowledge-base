# 📖 【암기용】 개념 완전 이해

> 목적: 문맥 자유 문법을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **문맥 자유 문법(CFG)**은 촘스키 위계 Type 2에 해당하는 언어로, 주변 문맥(Context)에 상관없이 하나의 비단말 기호를 다른 기호들로 치환할 수 있는 문법이다.
- **왜 필요한가**: 프로그래밍 언어의 '괄호 열고 닫기', 'if-else 중첩' 같은 계층적·재귀적 구조는 기억력이 없는 정규 언어(Type 3)로는 표현할 수 없기 때문이다.
- **핵심 직관**: "A는 B와 C로 이루어진다"는 식의 트리 구조(문법 트리)를 만들 수 있는 규칙이다. 앞뒤에 무슨 단어가 오든 A는 항상 B와 C로 전개되므로 '문맥에서 자유롭다'고 부른다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 비단말 기호 (Non-terminal) | 문법 구조를 나타내며 다른 기호로 전개 가능한 기호 | `<문장>`, `<주어>` 같은 껍데기 |
| 단말 기호 (Terminal) | 더 이상 전개되지 않는 최종 기호 (어휘 토큰) | `if`, `(`, `123` 같은 실제 단어 |
| 생성 규칙 (Production) | $A \rightarrow \alpha$ 형태의 치환 규칙 | `<문장>` $\rightarrow$ `<주어>` `<동사>` |
| 푸시다운 오토마타 (PDA) | 스택(Stack)을 가진 인식 기계 | 기억력(스택)이 생긴 괄호 검사기 |

## 깊이 이해
- **배경·문제의식**: 정규 문법은 $a^n b^n$ (a가 n번, 그다음 b가 n번) 형태를 인식하지 못한다. 괄호가 열린 만큼 닫혀야 하는 프로그래밍 언어를 구문 분석하려면, 몇 번 열렸는지 기억할 무언가가 필요했다.
- **작동 원리**: CFG의 생성 규칙은 좌변이 반드시 '단일 비단말 기호'다. 즉 $\alpha A \beta \rightarrow \dots$ 처럼 주변 문맥($\alpha, \beta$)을 보지 않고 오직 $A$만 보고 치환한다. 이를 인식하는 푸시다운 오토마타(PDA)는 여는 괄호를 스택에 Push하고 닫는 괄호에 Pop하여 짝을 맞춘다.
- **비유**: 식당 메뉴판에서 '세트 A = 버거 + 감튀 + 콜라'라고 적혀 있다면, 앞뒤에 어떤 메뉴를 시키든 '세트 A'는 항상 저 구성이다. 문맥과 무관하게 치환된다.
- **구체 예시**:
  - $S \rightarrow (S) \mid \epsilon$ : 완벽하게 짝이 맞는 괄호 문자열을 무한히 생성하는 규칙.
- **흔한 오해·주의점**: 이름이 "자유"라서 규칙이 없다고 오해하기 쉽지만, 오히려 좌변에 기호가 딱 1개만 와야 한다는 점에서 문맥 의존 문법(Type 1)보다 '제약이 더 강한' 문법이다.

## 연결 개념
- 구문 분석 트리 (AST) — CFG를 통해 파생된 계층 구조
- 컴파일러 파서 (LL, LR) — CFG를 분석하는 알고리즘
- 백나우어 표기법 (BNF) — CFG를 서술하는 표준 표기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 문맥 자유 문법(CFG)은 좌변에 단일 비단말 기호만 가지는 생성 규칙($A \rightarrow \alpha$)의 집합으로, 촘스키 Type 2 언어를 정의한다.
> 2. **가치**: 스택(Stack) 메모리를 활용하는 푸시다운 오토마타(PDA)로 인식 가능하여, 괄호 매칭과 제어문 중첩 같은 재귀적 계층 구조를 $O(n^3)$ 이하로 표현·분석할 수 있다.
> 3. **판단 포인트**: 프로그래밍 언어의 구문(Syntax)은 대부분 모호성을 제거한 결정론적 CFG로 설계되며, LL(하향식)/LR(상향식) 파싱 알고리즘의 기반이 된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로그래밍 언어 구문 분석의 이론적 기반 확인 | Type 2 언어, 스택(PDA), BNF 표기법, AST 생성 | '자유롭다'는 단어를 유연함으로 오역하여 서술 |
| 생성 규칙의 제약 조건 지식 | $A \rightarrow \alpha$ (좌변이 단일 비단말 기호) | $aAb \rightarrow acb$ 같은 문맥 의존 규칙과 혼동 |
| 컴파일러 구문 분석(Parsing) 구조 이해 | 구문 분석 트리, LL(Top-down) 파서와 LR(Bottom-up) 분기 | 어휘 분석(정규 언어) 단계와 구문 분석 단계를 혼용 |

> 요약: CFG가 스택을 이용해 계층 구조를 어떻게 처리하며, 이것이 컴파일러의 파싱 트리(AST)와 파서 설계로 어떻게 이어지는지 구조화해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 좌변의 비단말 기호가 주변 문맥에 관계없이 독립적으로 우변으로 치환되는 생성 규칙 기반의 언어 문법
- 배경: 정규 문법(Type 3)은 상태 기억의 부재로 재귀적 중첩 구조(예: $a^n b^n$, 괄호 매칭) 처리가 불가능
- 필요성: 프로그래밍 언어의 중첩된 블록, 수식 계층을 결정론적으로 분석하고 파싱 트리(추상 구문 트리)를 구축하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
문맥 자유 문법의 4원소 구조 튜플: G = (V, T, P, S)
시작 기호(S) -> 생성 규칙(P) 반복 적용 -> 비단말 기호(V) 치환 -> 단말 기호(T) 조합
                                           |
                                           +-> 파싱 트리(AST)로 계층화
```

| 구성요소 | 기호 | 역할 및 제약 |
|:---|:---:|:---|
| 비단말 기호 (Variables) | $V$ | 다른 기호로 치환될 수 있는 중간 상태 변수 (예: Expression) |
| 단말 기호 (Terminals) | $T$ | 더 이상 치환되지 않는 알파벳 집합 (어휘 토큰 집합) |
| 생성 규칙 (Productions) | $P$ | $A \rightarrow \alpha$ ($A \in V$, $\alpha \in (V \cup T)^*$) 형태의 변환 규칙 |
| 시작 기호 (Start Symbol) | $S$ | 문법 파생이 시작되는 최초의 비단말 기호 ($S \in V$) |

> 요약: 문맥 자유 문법은 오직 단일 비단말 기호를 우변의 기호 열로 치환하는 엄격한 구조를 통해 계층적 트리를 형성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
푸시다운 오토마타(PDA)의 중첩 구조 인식 흐름 (예: 괄호 매칭)
토큰 입력 -> [열림] 스택 Push -> [닫힘] 스택 Pop 비교 -> 스택 Empty 여부로 검증
```

- 1단계 [토큰열 입력]: 어휘 분석기에서 생성된 단말 기호(토큰) 스트림을 차례로 입력받음
- 2단계 [스택 전이]: 입력 기호와 스택의 최상단 기호(Top)를 확인하여 Push, Pop 또는 상태 전이 수행
- 3단계 [구문 트리 구축]: 파생 과정에 따라 하향식(전위 순회) 또는 상향식(역방향 치환)으로 트리를 그림
- 4단계 [검증·출력]: 입력 소진 시 스택이 비워지고(Accept) 유효한 추상 구문 트리(AST)를 다음 단계로 전달

> 요약: 스택을 통해 과거에 열린 괄호와 계층 깊이를 기억하므로, 중첩된 구문의 완전성을 범용 $O(n^3)$ 한도 내에서 검증할 수 있다.

---

## Ⅳ. 특징

- 재귀성 표현: $A \rightarrow aAb$와 같이 규칙 내에 자신을 포함할 수 있어 무한한 중첩 깊이 표현 가능
- 결정성(DCFG) 파싱 한정: O(n³)의 범용 CFG 파싱은 비효율적이므로, 컴파일러는 선독(Lookahead) 토큰으로 백트래킹 없이 $O(n)$ 파싱 가능한 결정론적 CFG(LL/LR)를 사용
- 모호성(Ambiguity) 리스크: 동일한 문자열에 대해 2개 이상의 서로 다른 파싱 트리가 만들어질 수 있으며, 언어 설계 시 연산자 우선순위 등으로 모호성을 제거해야 함

> 요약: 계층 표현력이 뛰어나지만, 모호성을 방지하기 위해 문법을 LR(1) 등의 결정론적 부분집합으로 통제하는 것이 핵심이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 문맥 자유 문법 (CFG) | 문맥 의존 문법 (CSG, Type 1) | 선택 기준 |
|:---|:---|:---|:---|
| 생성 규칙 형태 | $A \rightarrow \alpha$ | $\alpha A \beta \rightarrow \alpha \gamma \beta$ | 문맥 독립성 vs 문맥 종속성 |
| 인식 기계 | 푸시다운 오토마타 (PDA) | 선형 한계 오토마타 (LBA) | 스택(LIFO) vs 유한 테이프 |
| 프로그래밍 파싱 | 구문 분석 (Syntax Analysis) | 의미 분석 (Semantic Analysis) | AST 구축 vs 타입·변수 스코프 검증 |

> 요약: 컴파일러는 성능을 위해 구문 분석은 문맥 자유 문법(AST 생성)으로, 변수 선언 여부 등 문맥이 필요한 의미 분석은 심볼 테이블(Symbol Table)을 활용하여 별도로 분리 처리한다.

**리스크·대응 (기본 불릿):**
- 문법 모호성: "Dangling-Else" 문제 등 모호한 구조 발생 → 연산자 우선순위 결합성 명시 및 좌인수분해(Left Factoring) 적용 (지표: 파싱 트리 유일성 확보)
- 좌재귀(Left Recursion) 무한 루프: 하향식 파서(LL)에서 $A \rightarrow A\alpha$ 무한 루프 발생 → 우재귀(Right Recursion)로 문법 구조 변환 (지표: 하향식 파싱 에러율 0%)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 파서 자동화: Yacc, Bison, ANTLR 등의 파서 제너레이터에 CFG를 BNF 표기법으로 입력하여 고성능 LR 파서를 자동 생성
2. DSL(도메인 특화 언어) 설계: 사내 비즈니스 룰 엔진이나 질의어(Query Language)를 설계할 때 CFG 기반 규칙으로 문법 모호성 사전 차단
3. 정적 분석 도구 연동: SonarQube 등에서 소스 코드의 CFG를 분석해 생성된 AST 트리를 순회하며 취약점 패턴 및 안티패턴 탐지

**결론 (2줄):**
- 기술사 판단: 정규 언어가 단어(토큰)를 식별한다면 CFG는 문장(구조)을 파악하는 핵심 뼈대이므로, 프로그래밍 언어와 통신 프로토콜 구문 설계 시 필수적이다.
- 향후 방향: 현대의 파싱 트렌드는 문법 모호성에 강하고 에러 복구가 뛰어난 GLL/GLR 파싱이나 오류 내성을 갖춘 PEG(Parsing Expression Grammar) 도입으로 발전하고 있다.
