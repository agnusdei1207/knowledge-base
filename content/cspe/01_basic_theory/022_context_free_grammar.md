## Ⅰ. 개요
- 정의: 촘스키 계층 Type 2 문법으로, 생성 규칙의 좌변이 단일 논터미널인 문법임
- 배경/필요성: 프로그래밍 언어의 구문(Syntax) 정의 및 파싱 과정에서 필수적임
- 출제 의도: CFG의 구조, 유도 과정, 모호성(Ambiguity) 해결 능력 측정

## Ⅱ. 구성요소
- ASCII 구조도
      [S] (Start Symbol)
     /   \
  [A]     [B] (Non-terminals)
   |       |
  'a'     'b' (Terminals)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 푸시다운 오토마타 | CFG를 수용하는 스택 기반 인식기 | 메모리 소유 로봇 |
| 스택 (Stack) | 논터미널과 터미널을 저장하는 LIFO 메모리 | 작업대 |
| 생성 규칙 | A -> γ (γ는 문자열) 형태의 규칙 | 조립 매뉴얼 |
| 파스 트리 | 문장의 계층적 유도 과정을 나타낸 트리 | 설계도 |
> 요약: CFG는 스택 메모리를 활용하여 재귀적 구조(중첩)를 표현할 수 있는 문법임

## Ⅲ. 절차
- ASCII 흐름도
  [Input String] -> [Parser] -> [Derivation] -> [Parse Tree]

1. 문법 설계: 언어의 구문 규칙을 BNF 또는 EBNF 형태로 정의함
2. 좌측/우측 유도: 생성 규칙을 적용하여 문자열을 단계적으로 생성함
3. 모호성 제거: 하나의 문장에 대해 두 개 이상의 트리가 생기지 않도록 수정함
4. 파싱 알고리즘 적용: LL, LR 등의 기법을 통해 실제 구문 분석을 수행함
> 요약: 유도 과정을 통해 파스 트리를 생성하며 구문의 정당성을 검증함

## Ⅳ. 문제점
- 모호성 문제: 동일 문장에 대해 여러 해석이 가능하여 컴파일러 오류 유발함
- 성능 한계: 일반적인 CFG 파싱은 O(n^3)의 시간 복잡도를 가질 수 있음

## Ⅴ. 개선방안
- 문법 정규화: Chomsky Normal Form(CNF) 등으로 변환하여 알고리즘 효율화함
- 결정적 CFG: DCFG와 LR 파서를 사용하여 O(n)의 선형 시간 내 처리함

## Ⅵ. 전망
- 정형 코드 생성: 미션 크리티컬 소프트웨어의 무결성 증명을 위해 정형 방법론과 결합된 결함 없는 자동 코드 생성 엔진의 핵심 논리로 진화함
- 도메인 특화 언어(DSL): 클라우드 인프라(IaC)나 스마트 컨트랙트 등 특정 산업 도메인 언어의 신속한 설계와 파서 자동 생성을 지원함
- CSF: 문법의 모호성을 설계 단계에서 제거하고, LR 파싱 테이블 최적화를 통한 구문 분석의 선형 시간(O(n)) 성능 확보가 성공 요인임
