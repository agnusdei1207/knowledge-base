## Ⅰ. 개요
- **정의**: 중간 코드 또는 목적 코드의 실행 시간·메모리 사용량을 줄이면서 동일한 의미를 보존하는 변환 과정
- **배경/필요성**: 동일 로직이라도 코드 표현 방식에 따라 실행 성능 차이가 크므로, 자동화된 변환으로 성능을 개선할 필요가 있음
- **비유**: 같은 목적지로 가는 경로 중 신호등이 적고 거리가 짧은 경로를 자동 선택하는 내비게이션과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기계 독립/종속 최적화 구분 | 지역 최적화 vs 전역 최적화 vs 루프 최적화 분류 | 최적화는 의미 보존(Semantic Preserving)이 전제라는 점 명시 필요 |

> 요약: 프로그램 의미를 보존하면서 실행 성능을 개선하는 코드 변환 과정임

## Ⅱ. 구성요소
```text
  Intermediate Code
       |
       v
  +------------+     +------------+     +------------+
  | Local Opt  |---->| Global Opt |---->| Loop Opt   |
  | (기본블록) |     | (CFG 전체) |     | (반복구조) |
  +------------+     +------------+     +------------+
       |                                      |
       v                                      v
  Machine-Indep.                        Machine-Dep.
  Optimization                          Optimization
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Local Optimization | 기본 블록(Basic Block) 내에서 상수 폴딩·복사 전파·죽은 코드 제거를 수행함 | 한 방 안에서 불필요한 물건을 정리하는 작업 |
| Global Optimization | 제어 흐름 그래프(CFG) 전체를 분석하여 공통 부분식 제거·코드 이동을 수행함 | 건물 전체 동선을 분석해 비효율 경로를 재배치하는 작업 |
| Loop Optimization | 루프 불변 코드 이동·강도 축소·루프 언롤링 등 반복 구조 특화 최적화를 수행함 | 매번 반복하는 준비 작업을 루프 밖으로 빼는 것 |
| Machine-Dep. Optimization | 레지스터 할당·명령어 스케줄링 등 목적 기계 특성에 맞는 최적화를 수행함 | 특정 차량에 맞게 부품 배치를 조정하는 작업 |

> 요약: 지역·전역·루프·기계 종속 최적화가 단계적으로 코드 품질을 개선함

## Ⅲ. 절차
```text
  CFG구성            데이터흐름분석     변환적용          검증
  (기본블록분할)     (Reaching Def,    (폴딩/전파/       (의미보존확인)
                     Live Variable)    이동/언롤링)
       |              |              |              |
       +---분석------->+---탐지------->+---적용------->+
    기본블록/간선     최적화기회식별   코드변환수행     변환정당성검증
```
- 1단계: 중간 코드를 기본 블록으로 분할하고 제어 흐름 그래프(CFG)를 구성함
- 2단계: Reaching Definition·Live Variable 등 데이터 흐름 분석으로 최적화 가능 지점을 식별함
- 3단계: 상수 폴딩·복사 전파·루프 불변 코드 이동·강도 축소 등 변환을 적용함
- 4단계: 변환 전후 프로그램의 의미 동치성을 검증하여 정당성을 확인함

> 요약: CFG 구성 → 데이터 흐름 분석 → 변환 적용 → 의미 보존 검증 순서로 수행함

## Ⅳ. 문제점
- 분석 비용 증가: 전역 데이터 흐름 분석은 프로그램 크기에 비례하여 컴파일 시간을 증가시킴
- 변환 간 간섭: 하나의 최적화가 다른 최적화의 적용 가능성을 소멸시키는 Phase-Ordering 문제 발생함
- 디버깅 난이도 상승: 최적화된 코드와 소스 코드 간 대응 관계가 깨져 디버깅 정보의 정확도가 저하됨

> 요약: 분석 비용·Phase-Ordering·디버깅 난이도가 코드 최적화의 주요 과제임

## Ⅴ. 개선방안
1. 단기: SSA(Static Single Assignment) 형태 IR을 도입하여 데이터 흐름 분석 비용을 축소함
2. 중기: 반복 적용(Iterative) 프레임워크로 최적화 패스 순서를 자동 탐색하여 Phase-Ordering 문제를 완화함
3. 장기: DWARF 디버그 정보 갱신을 최적화 패스에 통합하여 변환 후에도 소스 매핑을 유지함

> 요약: SSA IR·반복 패스 탐색·디버그 정보 통합으로 최적화 한계를 극복함

## Ⅵ. 전망
- 발전 방향: ML 기반 컴파일러 최적화(AutoTuning)가 패스 순서·파라미터 선택을 자동화하는 방향으로 연구 진행 중임
- 기술사적 판단: 최적화 수준이 동일 하드웨어에서의 응용 성능을 결정하므로 시스템 소프트웨어 경쟁력의 핵심임
- 기술사 제언: 최적화 기법 개별 암기보다 데이터 흐름 분석 프레임워크의 원리를 이해하는 것이 응용력 확보에 유리함
