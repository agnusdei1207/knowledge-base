# 동적 프로그래밍 (Dynamic Programming)

## 1. 개요

- **정의/개념**: 동적 프로그래밍(Dynamic Programming, DP)은 중복 부분 문제의 결과를 상태로 저장·재사용하여 최적값, 경우의 수, 가능 여부를 계산하는 알고리즘 설계 기법이다.
- **배경/필요성**: 단순 재귀는 같은 부분 문제를 반복 계산해 지수 시간이 될 수 있으므로, 상태와 점화식을 정의해 계산량을 상태 수 수준으로 줄일 필요가 있다.

DP는 모든 문제에 적용되는 기법이 아니라 중복 부분 문제와 최적 부분 구조가 있을 때 효과적이다.

## 2. 특징 및 비교

| 구분 | 단순 재귀 | 동적 프로그래밍 | 탐욕 알고리즘 |
|---|---|---|---|
| 계산 방식 | 동일 부분 문제 반복 | 결과 저장·재사용 | 매 단계 최선 선택 |
| 적용 조건 | 구조 표현이 쉬움 | 중복 부분 문제, 최적 부분 구조 | 탐욕 선택 속성 |
| 정확성 | 문제에 따라 다름 | 점화식이 맞으면 보장 | 증명 필요 |
| 비용 | 지수 시간 가능 | 상태 수에 비례 | 대체로 낮음 |

Top-down 메모이제이션은 재귀 구조를 유지하며 필요한 상태만 계산하고, Bottom-up 방식은 작은 상태부터 표를 채워간다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| 상태(State) | 부분 문제를 구분하는 변수 | 제약과 목표 포함 |
| 점화식 | 이전 상태로 현재 상태를 계산하는 관계 | 전이 조건 정확성 |
| 초기값 | 계산 시작 기준 | 경계 조건 |
| 계산 순서 | 참조 상태가 먼저 계산되도록 정한 순서 | 위상 순서 |
| 저장 테이블 | 상태별 결과 저장 공간 | 시간-공간 트레이드오프 |

```text
상태 정의 -> 점화식 수립 -> 초기값 설정 -> 계산 순서 결정 -> 최종 상태 반환
```

## 4. 문제점 및 개선방안

1. **상태 폭발**
   - 상태 변수가 많아지면 시간·메모리가 급격히 증가한다.
   - **개선방안**: 상태 압축, sparse table, 가지치기, meet-in-the-middle을 적용한다.

2. **점화식 오류**
   - 상태가 제약을 충분히 담지 못하면 표를 채워도 실제 해가 되지 않는다.
   - **개선방안**: 작은 입력의 완전탐색 결과와 DP 결과를 비교한다.

3. **계산 순서·초기값 오류**
   - 참조 상태가 아직 계산되지 않거나 기본 상태가 틀리면 전체 결과가 오염된다.
   - **개선방안**: 초기값 표와 반복문 방향을 명시하고 경계 입력 테스트를 수행한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 최적화 문제 | 배낭 문제, 경로 최적화, 자원 배분에 상태·점화식 적용 | 최적값, 상태 수 |
| 문자열 처리 | 편집 거리, LCS, 시퀀스 정렬 계산 | 정확도, 테이블 크기 |
| 머신러닝·확률 모델 | Viterbi, 동적 계획 기반 추론 | 추론 시간, 메모리 |

## 6. 결론

동적 프로그래밍은 중복 계산을 제거해 지수적 재귀를 상태 수 기반 계산으로 바꾸는 강력한 기법이다. 핵심은 상태 정의와 점화식이며, 메모리 폭증과 초기값·계산 순서 오류를 함께 관리해야 한다.
