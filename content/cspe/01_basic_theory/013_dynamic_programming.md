## 미리 알고가기

- 중복 부분 문제(Overlapping Subproblems): 큰 문제를 해결하기 위해 계산한 작은 문제의 답이 반복적으로 다시 나타나는 성질임
- 최적 부분 구조(Optimal Substructure): 작은 문제의 해를 조합해 큰 문제의 해를 구성할 수 있는 성질임
- 메모이제이션(Memoization): 하향식(Top-down) 접근에서 계산한 부분 문제의 답을 캐시에 저장하여 중복 계산을 방지하는 기법임
- 타뷸레이션(Tabulation): 상향식(Bottom-up) 접근에서 작은 문제부터 순서대로 답을 채워나가며 최종 해를 구하는 기법임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 중복 부분 문제와 부분 문제 의존성이 있는 문제를 상태로 모델링하고, 계산한 상태값을 저장해 동일 상태를 다시 계산하지 않도록 하는 알고리즘 설계 기법임
- **배경/필요성**: 단순 재귀나 완전 탐색에서 같은 상태가 반복되면 실행 시간이 재방문 횟수에 따라 커지므로, 상태 수와 전이 비용을 기준으로 계산량을 통제하는 저장 전략이 필요함

## Ⅱ. 특징

- 동일 상태를 한 번만 계산하고 저장된 값을 재사용하므로, 전체 비용을 상태 수와 상태 전이 비용 중심으로 제한함
- 상태를 정의하는 변수의 개수와 범위에 따라 시간·공간 복잡도가 함께 커지므로, 문제 해결에 필요한 최소 상태를 설계해야 함
- 점화식이 현재 상태와 이전 또는 하위 상태의 의존 관계를 표현하므로, 초기값과 계산 순서가 맞아야 상태값이 일관되게 누적됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 하향식 ($Top-down$) | 상향식 ($Bottom-up$) |
|:---|:---|:---|
| **핵심 기법** | 메모이제이션 ($Memoization$) | 타뷸레이션 ($Tabulation$) |
| **수행 방식** | 큰 문제부터 재귀적으로 호출 | 작은 문제부터 반복문으로 누적 |
| **장점** | 도달한 상태만 계산해 불필요한 상태 계산을 줄일 수 있음 | 재귀 오버헤드가 없고 스택 관리가 용이함 |
| **단점** | 재귀 깊이가 깊어지면 스택 한계에 도달함 | 정답과 상관없는 모든 상태를 계산해야 함 |
| **대표 도구** | 재귀 함수, 해시/배열 캐시 | 반복문, $DP$ 테이블 (배열) |

> 요약: 도달 상태가 일부이고 재귀 구조가 자연스러우면 하향식을, 의존 순서가 명확하고 스택 사용을 피해야 하면 상향식을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 ($State$) | 부분 문제를 유일하게 식별하는 변수 조합이며, 저장소에서 해를 조회하는 인덱스 역할을 함 |
| 점화식 | 현재 상태의 값을 이전 상태들의 조합으로 산출하기 위한 수학적 관계식임 |
| 기저 사례 (Base Case) | 점화식이 참조하는 시작 상태 또는 경계 조건의 확정값임 |
| 저장소 (Memo/Table) | 계산된 상태값을 저장해 이후 전이 계산이나 재귀 호출에서 재사용하는 메모리 구조임 |

```text
[ DP 구조 모델 ]
State f[i] ---> Recurrence f[i] = f[i-1] + f[i-2]
      |                         |
      v                         v
Base f[0], f[1] ---------> Memo/Table ---------> Target f[n]
```

> 요약: DP는 상태를 인덱스로 삼아 점화식과 초기값을 연결하고, 저장소가 계산된 상태값을 재사용하게 만드는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 상태 정의    | --> | 점화식 수립   | --> | 초기값 설정   | --> | 상태값 계산  |
| (부분 문제)  |     | (전이 관계)  |     | (경계 조건)  |     | (저장/재사용)|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **상태 정의** — 전체 문제를 해결하기 위해 필요한 최소한의 변수들을 추출하고, 부분 문제의 의미를 명확히 정의함
2. **점화식 수립** — 현재 상태값을 이전 또는 하위 상태값으로부터 도출하는 전이 관계를 수식으로 작성함
3. **초기값 설정** — 점화식의 시작점이 되는 가장 작은 단위의 문제들에 대해 확정된 값을 저장소에 먼저 입력함
4. **해 누적** — 설정된 순서(상향식/하향식)에 따라 점화식을 적용하며 저장소를 채워나가고, 최종 목표 상태의 값을 추출함

> 요약: 상태 정의와 점화식이 맞아야 계산 순서와 저장 전략이 의미를 가지며, 최종 목표 상태의 값도 신뢰할 수 있음.

## Ⅵ. 실무 적용 및 유의점

1. 배낭 문제나 편집 거리처럼 상태 공간이 큰 DP에서는 상태 변수를 늘릴수록 실행 시간과 메모리가 함께 증가하므로, 필요한 변수만 남기고 슬라이딩 윈도우 같은 축약 기법을 적용하며 상태 수와 최대 메모리 사용량을 확인해야 함
2. 점화식의 논리 오류가 있으면 모든 후속 상태값이 왜곡되므로, 경계 조건과 작은 입력의 완전 탐색 결과를 대조하고 계산된 상태 수와 캐시 적중률로 재사용 효과를 확인해야 함

## Ⅶ. 결론

- 동적 프로그래밍은 중복 부분 문제를 상태 수와 전이 비용으로 통제하는 기법이므로, 상태 정의·점화식·저장 전략을 함께 검증해야 함
