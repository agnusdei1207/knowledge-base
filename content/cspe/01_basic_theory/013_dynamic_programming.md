# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 동적 프로그래밍(DP)은 **알고리즘 설계 패러다임**의 하나로, **한 번 푼 부분 문제의 답을 저장(메모)해 두고 재사용**함으로써 같은 부분 문제를 반복 계산하는 낭비를 없애 지수 시간을 다항 시간으로 낮추는 기법이다.
- **왜 필요한가**: 부분 문제가 서로 겹치는 문제를 단순 재귀로 풀면 같은 계산을 지수적으로 반복하기 때문에, 답을 한 번만 계산하고 표에 채워 재사용해야 하기 때문이다.
- **핵심 직관**: "**한 번 계산한 답은 두 번 다시 계산하지 않는다**" — 작은 문제의 답을 적어 두고, 큰 문제는 그 적어 둔 답을 조립해서 만든다.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안용 Ⅰ~Ⅵ·표에 나오는 DP 고유 표기를 비유와 함께 먼저 세운다(O(2^N)↔O(N) 같은 복잡도 의미는 001·002 참조). 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 동적 프로그래밍 (상위 키워드) | 겹치는 부분 문제의 답을 저장·재사용하는 설계 패러다임 | 계산한 답을 장부에 적어 두고 다시 씀 |
| 부분 문제 (Subproblem) | 원 문제를 같은 형태로 잘게 나눈 작은 문제 | 피보나치 F(5)를 풀려면 F(4)·F(3)이 필요 |
| 중복 부분 문제 (Overlapping) | 여러 상위 문제가 같은 작은 문제를 다시 필요로 함 | F(4)와 F(3) 둘 다 F(2)를 또 계산 |
| 최적 부분 구조 (Optimal Substructure) | 부분 문제의 최적해를 합치면 전체 최적해가 됨 | 각 구간 최단 경로를 이으면 전체 최단 |
| 메모이제이션 (Memoization) | 재귀로 풀되 계산한 답을 캐시에 저장(Top-Down) | 위에서 내려가며 답을 메모지에 적음 |
| 타뷸레이션 (Tabulation) | 작은 문제부터 표를 채워 올림(Bottom-Up) | 표 1행부터 순서대로 빈칸을 메움 |
| 점화식 (Recurrence) | 큰 문제 답을 작은 문제 답으로 정의한 식 | F(n)=F(n-1)+F(n-2) |
| 상태(State)·상태 전이 | 부분 문제를 식별하는 변수와 그 값의 갱신 규칙 | 표의 칸(상태)과 칸을 채우는 규칙 |

## 깊이 이해
- **배경·문제의식**: 피보나치 F(n)을 단순 재귀로 풀면 F(n-1)과 F(n-2)가 각각 다시 F(n-3)…을 호출해 **같은 값을 O(2^N)번** 중복 계산한다. 부분 문제가 겹치는데도 매번 새로 푸는 것이 낭비의 근원이며, DP는 이 답을 **한 번만 계산해 저장**해 O(N)으로 낮춘다.
- **작동 원리 (어떻게+왜)**:
  - **적용 조건 두 가지**: ① **중복 부분 문제** — 같은 작은 문제가 반복 등장해야 저장의 이득이 생김, ② **최적 부분 구조** — 부분 최적해를 합쳐 전체 최적해가 나와야 점화식이 성립함. 둘 다 만족해야 DP가 옳다.
  - **Top-Down(메모이제이션)**: 원 문제에서 재귀로 내려가되, 캐시에 답이 있으면 즉시 반환한다. 코드가 점화식과 닮아 직관적이나 재귀 호출 스택(001 참조) 비용이 든다.
  - **Bottom-Up(타뷸레이션)**: 가장 작은 문제부터 표를 채워 올린다. 재귀 오버헤드가 없고, 필요한 이전 값만 남기는 **롤링 배열**로 공간을 O(N)→O(1)까지 줄일 수 있다.
- **비유**: 시험 족보와 같다. 한 번 푼 문제의 풀이를 장부에 적어 두면, 다음에 같은 문제가 나올 때 다시 풀지 않고 장부만 펼쳐 베낀다. 장부(표)를 채우는 순서가 Bottom-Up이다.
- **구체 예시(수치·사례)**: 0/1 배낭 문제(용량 W, 물건 N개)를 DP로 풀면 `dp[i][w]`(i번째까지 고려·용량 w일 때 최대 가치) 표를 채워 O(NW)에 최적해를 구한다. 최장 공통 부분 수열(LCS)은 O(mn), 편집 거리(Edit Distance)도 O(mn) 표로 푼다. 피보나치는 롤링 배열로 O(N) 시간·O(1) 공간이 된다.
- **흔한 오해·주의점**:
  - **DP는 무조건 빠르다는 오해** — 부분 문제가 겹치지 않으면 저장할 이득이 없어 분할 정복(014)이 맞다. DP는 "겹칠 때"만 이득이다.
  - **최적 부분 구조가 없으면 DP가 틀린 답을 낸다** — 최장 단순 경로(longest simple path)는 부분 최적해를 합쳐도 전체 최적이 안 되므로 DP로 못 푼다.
  - **메모이제이션과 타뷸레이션은 같은 DP** — 방향(하향/상향)만 다를 뿐 저장·재사용 원리는 동일하다.

## 연결 개념
- **분할 정복 (014)**: 문제를 부분으로 쪼갠다는 점은 같으나, 분할 정복은 부분 문제가 **독립(안 겹침)**이라 저장이 무의미하다는 대비 개념.
- **탐욕 알고리즘 (015)**: 둘 다 최적화 문제를 풀지만, 탐욕은 되돌아보지 않는 국소 선택, DP는 모든 경우를 표에 남겨 비교하는 대비 개념.
- **최단 경로 (011)**: 벨만-포드·플로이드-워셜이 DP 점화식(최적 부분 구조)으로 최단 경로를 채우는 대표 응용.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DP는 중복 부분 문제의 답을 저장·재사용해 지수 시간을 다항 시간으로 낮추는 설계 패러다임임.
> 2. **가치**: 배낭·LCS·편집 거리·최단 경로 등 겹치는 부분 문제를 가진 최적화 문제를 다항 시간에 정확히 해결함.
> 3. **판단 포인트**: 중복 부분 문제와 최적 부분 구조 두 조건이 모두 성립할 때만 적용해야 유효함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 적용 조건 이해 | 중복 부분 문제·최적 부분 구조 2조건 | 적용 조건 언급 누락 |
| 두 구현 방식 구분 | 메모이제이션(Top-Down)·타뷸레이션(Bottom-Up) | 두 방식을 별개 알고리즘으로 오인 |
| 분할 정복과의 차이 | 부분 문제 중복 여부가 갈림 | DP를 단순 재귀와 동일 단정 |

> 요약: DP 2조건(중복 부분 문제·최적 부분 구조)과 두 구현 방식, 분할 정복과의 부분 문제 중복 차이를 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 겹치는 부분 문제의 답을 저장·재사용해 반복 계산을 없애는 최적화 설계 패러다임임
- 배경: 단순 재귀는 같은 부분 문제를 지수적으로 중복 계산해 O(2^N)로 폭증함
- 필요성: 배낭·경로·문자열 정렬 등 부분 문제가 겹치는 최적화 문제를 다항 시간에 정확히 풀 필요가 있음

## Ⅱ. 구조 및 구성요소
선형 구조도 (점화식 기반 표 채우기):

    원 문제 정의 -> 상태·점화식 설계 -> 부분 문제 답 저장(표/캐시) -> 재사용으로 전체 최적해 조립
      / Top-Down : 재귀 하향 + 메모이제이션 캐시 조회
      / Bottom-Up : 작은 문제부터 표 상향 채움 + 롤링 배열로 공간 절감

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 상태·점화식 | 부분 문제를 식별하고 답을 정의 | DP 설계의 핵심, 잘못되면 오답 |
| 메모이제이션 캐시 | 계산한 답을 저장해 재귀 중복 차단 | Top-Down, 재귀 스택 비용 존재 |
| DP 표(테이블) | 작은 문제 답을 순서대로 저장 | Bottom-Up, 재귀 오버헤드 없음 |
| 롤링 배열 | 직전 값만 유지해 공간 축소 | O(N)→O(1) 공간 최적화 가능 |

> 요약: 상태·점화식으로 부분 문제를 정의하고, 캐시(하향) 또는 표(상향)에 답을 저장·재사용해 전체 최적해를 조립함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (Bottom-Up 기준):

    부분 문제 정의 -> 점화식 도출 -> 초기값(base case) 설정 -> 작은 문제부터 표 채움 -> 최종 칸이 전체 최적해

1. 정의: 설계자가 부분 문제를 식별하는 상태 변수와 점화식(큰 문제=작은 문제 조합)을 세움
2. 초기화: 알고리즘이 가장 작은 문제(base case)의 답을 표에 직접 채움
3. 채움: 알고리즘이 작은 문제부터 점화식으로 각 칸을 계산하되 이미 채운 값을 재사용함
4. 종료: 표의 최종 상태 칸이 원 문제의 최적해가 되며 시간은 상태 수 × 전이 비용임

> 요약: 점화식과 초기값을 세운 뒤 작은 문제부터 표를 채워 재사용하며, 최종 칸이 전체 최적해가 됨.

## Ⅳ. 특징
- 지수→다항 단축: 중복 부분 문제의 답을 한 번만 계산해 O(2^N)를 상태 수 × 전이 비용의 다항 시간으로 낮춤
- 정확성 보장: 모든 부분 경우를 표에 남겨 비교하므로 탐욕과 달리 항상 전역 최적해를 산출함
- 공간-시간 트레이드오프: 표 저장에 O(N)~O(NW) 공간을 쓰며, 롤링 배열로 공간을 O(1)까지 절감 가능함
- 적용 제약: 최적 부분 구조가 없으면(예: 최장 단순 경로) DP가 성립하지 않아 오답을 냄
- 두 방향 동등성: 메모이제이션(하향)과 타뷸레이션(상향)은 저장·재사용 원리가 같은 동일 기법임

## Ⅴ. 심화 비교 및 적용 판단

부분 문제 중복 여부·저장 필요성·시간 효과 축에서 DP와 분할 정복을 대조함(분할 정복 vs 반복 대비는 014 참조).

| 구분 | 동적 프로그래밍 | 분할 정복(014) |
|:---|:---|:---|
| 부분 문제 관계 | 중복(서로 겹침) | 독립(안 겹침) |
| 답 저장 필요성 | 필수(재사용이 핵심 이득) | 불필요(재사용할 게 없음) |
| 대표 예 | 피보나치·배낭·LCS | 병합·퀵 정렬(003 참조) |
| 시간 효과 | 지수→다항 단축 | 분할로 O(N log N)급 |

> 요약: 부분 문제가 겹치면 DP로 저장·재사용해 지수 시간을 없애고, 겹치지 않으면 분할 정복이 맞음.

**리스크·대응:**
- 잘못된 점화식 — 상태·전이 설계 오류로 오답 → 작은 입력으로 브루트포스 결과와 대조 검증
- 최적 부분 구조 미성립 — 부분 최적 조합이 전체 최적이 아님 → 문제 구조 선증명 후 DP 적용
- 표 메모리 초과 — 상태 공간이 커 O(NW) 메모리 폭증 → 롤링 배열·필요 상태만 저장으로 축소

**점검 지표:**
- 정확성 — DP 결과 = 브루트포스 결과(소입력) — 무작위 테스트로 일치 확인
- 효율 — 각 상태 1회 계산 — 캐시 적중·중복 호출 0 확인

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 문자열 정렬·검색(편집 거리): 맞춤법 검사·DNA 서열 정렬에서 Edit Distance·LCS DP 표(O(mn))로 최소 편집·최장 공통 구간 계산
2. 자원 배분 최적화(배낭 DP): 예산·용량 제약 하 가치 최대화 문제를 `dp[i][w]` 표(O(NW))로 풀어 투자·적재 계획 산출
3. 최단 경로·비용(경로 DP): 벨만-포드·플로이드-워셜(011)의 DP 점화식으로 음수 간선·전 쌍 최단 비용을 안정적으로 계산

**결론:**
- 기술사 판단: 부분 문제가 겹치고 최적 부분 구조가 성립하면 DP, 겹치지 않으면 분할 정복(014)·최적성 미보장 허용이면 탐욕(015)을 택하는 조건부 선택이 유효함
- 향후 방향: 상태 공간이 큰 문제에서 근사 DP·강화학습의 가치 함수 근사로 대규모 순차 의사결정 최적화가 확장되고 있음
