## 미리 알고가기

- 중복 부분 문제: 같은 부분 문제가 여러 경로에서 반복 등장하는 성질임
- 최적 부분 구조: 최적화 문제의 전체 최적해를 부분 문제의 최적해로 구성할 수 있는 성질임
- 상태(State): 부분 문제를 유일하게 식별하는 입력 위치·남은 자원 등의 최소 변수 조합임
- 상태값: 각 상태에서 구하려는 최솟값·최댓값·경우의 수·가능 여부임
- 점화식: 현재 상태의 답을 더 작은 상태의 답과 현재 선택으로 표현한 계산식임
- 계단 예시: 한 번에 1칸 또는 2칸을 오를 때 $n$번째 계단까지의 경우의 수는 $dp[n]=dp[n-1]+dp[n-2]$로 구함
- 기저 사례: 점화식이 더 작은 상태를 참조하다 멈추는 시작값이며, 위 계단 문제는 $dp[0]=1$, $dp[1]=1$에서 시작함
- 메모이제이션: 재귀 호출로 필요한 상태를 계산·저장하고 같은 상태가 다시 호출되면 저장값을 반환하는 방식임
- 타뷸레이션: 기저 사례부터 의존 순서대로 상태값을 표에 저장해 목표 상태까지 계산하는 방식임

## 작성 근거(검토용)

- **개요 구성**: 동일한 부분 문제를 상태로 식별하고 저장한 답을 점화식에서 재사용하는 원리를 정의에 반영함
- **Ⅱ. 특징 선정**: 동일 상태의 동일 답, 최적 부분 구조, 점화식, 저장 재사용이 DP 성립을 가르는 핵심 조건임
- **Ⅲ 비교축 선정**: 하향식과 상향식의 계산 방향·계산 대상·실행 방식·의존성 처리·적합 조건·실행 실패 조건을 같은 질문으로 비교함
- **Ⅳ 구조 선정**: 상태·상태값·점화식·기저 사례·저장소·계산 순서가 DP 답을 만드는 관계를 설명함
- 제목부터 결론까지 모든 문장과 표 셀을 다섯 차례 전수 검수하고 각 비교 셀이 좌측 판단 기준에 직접 답하도록 교정함

## Ⅰ. 개요

- **정의/개념**: 동적 계획법은 동일한 부분 문제를 상태로 식별하고 각 상태의 답을 한 번만 계산·저장한 뒤 점화식에서 재사용하는 알고리즘 설계 기법임
- **배경/필요성**: 부분 문제를 분해할 때 같은 상태가 반복 계산되는 비용을 줄이기 위해 상태별 답을 저장·재사용하는 방식이 필요함

## Ⅱ. 특징

- 같은 상태는 어떤 경로로 도달해도 같은 답을 가져야 저장값을 재사용할 수 있음
- 최적화 문제는 부분 문제의 최적해로 전체 최적해를 구성할 수 있어야 함
- 점화식은 현재 상태의 답을 더 작은 상태의 답과 가능한 선택으로 표현함
- 메모이제이션이나 타뷸레이션으로 계산한 상태값을 저장해 중복 계산을 제거함

## Ⅲ. 종류 및 비교

| 판단 기준 | 하향식 ($Top-down$) | 상향식 ($Bottom-up$) |
|:---|:---|:---|
| 계산 방향 | 목표 상태에서 필요한 하위 상태를 재귀 호출함 | 기저 사례부터 목표 상태까지 반복 계산함 |
| 계산 대상 | 목표 상태에서 실제로 호출된 상태만 계산함 | 정의한 상태 공간에서 반복문이 순회하는 상태를 모두 계산함 |
| 실행 방식 | 메모이제이션 저장소와 재귀 호출 스택을 사용함 | DP 테이블과 반복문을 사용함 |
| 의존성 처리 | 재귀 반환 과정에서 하위 상태를 먼저 확정함 | 참조할 상태가 먼저 계산되도록 반복 순서를 정함 |
| 적합 조건 | 전체 상태 중 실제로 필요한 상태가 적을 때 | 의존 순서가 명확하고 대부분의 상태를 계산해야 할 때 |
| 실행 실패 조건 | 상태 의존 깊이가 호출 스택 한도를 넘을 때 | 필요한 DP 테이블 크기가 사용 가능한 메모리를 넘을 때 |

> 요약: 목표 상태에서 필요한 상태만 따라가면 하향식, 기저 사례부터 의존 순서대로 상태를 채우면 상향식임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 | 부분 문제를 입력 위치·남은 자원 같은 최소 변수 조합으로 유일하게 식별함 |
| 상태값 | 각 상태에서 구할 최솟값·최댓값·경우의 수·가능 여부를 정의함 |
| 점화식 | 현재 상태에서 가능한 선택별 하위 상태값을 결합해 현재 상태값을 계산함 |
| 기저 사례 | 점화식 없이 답을 아는 상태값으로 재귀 종료와 표 계산의 시작점을 제공함 |
| 저장소 | 계산된 상태값을 메모이제이션 캐시나 DP 테이블에 보관함 |
| 계산 순서 | 점화식이 참조하는 하위 상태를 현재 상태보다 먼저 확정함 |

> 요약: 상태의 의미와 상태값을 정하고 점화식·기저 사례·계산 순서를 맞춰 각 상태의 답을 한 번만 계산함.

## Ⅴ. 상태 설계 및 계산 절차

```text
하향식: 목표 상태 요청 -> 기저·저장값 확인 -> 미계산 하위 상태 호출 -> 점화식 계산 -> 저장·반환
상향식: 기저 사례 저장 -> 의존 순서로 상태 순회 -> 점화식 계산·저장 -> 목표값 반환
```

1. **상태 정의**: 부분 문제의 답을 결정하는 최소 변수만 상태에 포함함
2. **상태값 정의**: 각 상태에서 구할 최적값·경우의 수·가능 여부를 정함
3. **점화식 수립**: 현재 상태값을 하위 상태값과 가능한 선택으로 표현함
4. **기저 사례 설정**: 더 작은 상태를 참조하지 않는 시작값을 확정함
5. **계산·검증**: 하향식 또는 상향식으로 목표값을 구하고 작은 입력의 모든 후보를 확인한 결과와 대조함

> 요약: 하향식은 필요한 상태를 재귀로 확정하고 상향식은 기저 사례부터 의존 순서대로 상태값을 저장함.

## Ⅵ. 실무 사례

1. 문자열 유사도 서비스는 삽입·삭제·치환 최소 횟수를 상향식 DP로 계산하며, 직전·현재 행만 저장한 결과를 전체 테이블 결과와 대조하고 최대 메모리 사용량을 확인함
2. 빌드 작업 스케줄러는 선행 작업 완료 시간의 최댓값에 현재 작업 시간을 더하는 하향식 메모이제이션을 적용하고 상향식 결과와의 일치 여부·계산 상태 수를 확인함

## Ⅶ. 결론

- 동적 계획법은 중복 부분 문제를 상태로 유일하게 식별하고 점화식이 참조하는 하위 상태를 먼저 계산할 수 있을 때 적용하며 상태·전이·기저 사례를 작은 입력의 모든 후보 결과와 대조해야 함
