# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 복잡한 거대 문제를 작고 단순한 하위 문제로 쪼개서 푼 뒤, 그 '결과를 저장(캐싱)'해 두었다가 나중에 재사용함으로써 중복 연산을 제거하는 최적화 알고리즘 기법
- **왜 필요한가**: 재귀 호출을 막무가내로 쓰면 똑같은 계산을 수십억 번 반복하게 되어 시스템이 뻗는다(O(2^N)). 이를 캐시를 활용해 O(N)으로 마법처럼 단축하기 위해 필수적이다.
- **핵심 직관**: "기억해 두면 몸이 고생하지 않는다." 어제 푼 어려운 문제 정답을 노트에 적어두고, 오늘 똑같은 문제가 나오면 다시 계산하지 않고 노트에서 베껴 쓰는 것.

## 깊이 이해
- **배경·문제의식**: 피보나치 수열 50번째 값을 구하기 위해 `F(50) = F(49) + F(48)`을 생(Raw) 재귀로 호출하면, `F(2)` 같은 작은 연산이 수십억 번 중복되어 호출된다.
- **작동 원리 (2대 조건 필수)**:
  1. **최적 부분 구조**: 큰 문제의 정답을 작은 문제의 정답에서 구할 수 있어야 한다. (서울->부산 최단경로는 서울->대전 + 대전->부산이다).
  2. **중복되는 부분 문제**: 작은 문제가 여러 번 반복해서 등장해야 한다. (안 겹치면 그냥 분할 정복을 쓰면 된다).
- **구현 방식 2가지**:
  - **Top-Down (메모이제이션)**: 큰 것부터 호출하다가 모르면 아래로 내려가고, 답을 구하면 수첩(배열)에 적으며 올라온다. 재귀 사용.
  - **Bottom-Up (타뷸레이션)**: 제일 작은 바닥(인덱스 0)부터 차례대로 하나씩 답을 구해서 배열을 채워 올라간다. 반복문(For) 사용.
- **비유**: 
  - 분할 정복: 백과사전 편찬 (문학, 과학 등 파트가 겹치지 않아 각자 분담 후 취합).
  - DP: 구구단 외우기 (3*4를 알면 다음에 3*4가 나올 때 다시 계산하지 않고 바로 12를 말함).

## 연결 개념
- 분할 정복 (부분 문제가 중복되지 않음)
- 그리디 알고리즘 (매 순간 최선을 고르지만 미래를 보지 않음, DP는 미래까지 다 계산해봄)
- 최단 경로 (플로이드-워셜)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 거대 문제를 하위 문제로 분할한 뒤, 하위 문제의 해를 메모리에 저장(Memoization)하여 중복 연산을 O(1) 조회로 치환하는 최적화 패러다임이다.
> 2. **가치**: 지수 시간이 소요되는 복잡한 재귀 탐색 모델을 다항 시간 범위로 압축하여, 시스템의 연산 자원 고갈 한계를 돌파한다.
> 3. **판단 포인트**: 적용을 위해선 하위 해의 합이 상위 해가 되는 '최적 부분 구조'와 문제가 반복 호출되는 '중복 부분 문제' 속성을 점화식으로 증명해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 적용을 위한 필수 수학적 선결 조건 확인 | 1) 최적 부분 구조, 2) 중복되는 부분 문제 속성 명시 | DP를 단순한 캐싱 기술로만 취급하고 분할 구조 누락 |
| 분할 정복/그리디 등 타 패러다임과의 변별력 | 상호 배타적인 하위 문제(분할정복)와의 차이점 표기 | 하향식(메모이제이션)과 상향식(타뷸레이션) 용어 혼동 |

> 요약: DP는 코딩 스킬이 아니라, 반복되는 상태 전이를 점화식으로 도출해 공간-시간 복잡도를 교환하는 설계 수학이다.

## Ⅰ. 개요 및 필요성

- 정의: 복잡한 문제를 여러 하위 문제로 나누어 해결한 결과를 저장해두고, 추후 동일한 문제 발생 시 저장된 값을 재활용하는 알고리즘 기법
- 배경: 피보나치 등 상태 전이가 존재하는 재귀 호출 시, 중복 연산으로 인해 CPU 횟수가 지수 폭발하는 한계
- 필요성: 최단 경로(플로이드 워셜), 배낭 문제 등 완전 탐색 시 타임아웃이 걸리는 문제를 다항 시간 내에 서비스하기 위해 필수

## Ⅱ. DP 적용 필수 조건 및 구성요소

```text
문제 파악 -> [최적 부분 구조 검증] -> [중복 부분 문제 검증] -> 점화식(전이식) 도출 -> 캐시 배열 할당 및 갱신
```

| 구성요소 (조건) | 의미 | 성립 판단 기준 |
|:---|:---|:---|
| 최적 부분 구조 | 전체 문제의 최적해가 하위 문제들의 최적해로 구성됨 | 서울->부산 경로가 대전->대구 부분 경로의 합과 일치하는가? |
| 중복 부분 문제 | 동일한 하위 문제가 재귀 트리 상에서 여러 번 호출됨 | F(5)를 구하기 위해 F(2)가 3번 이상 반복 평가되는가? |
| 점화식 (수식) | 현재 상태를 이전 상태들의 관계로 정의한 수식 | `DP[i] = DP[i-1] + DP[i-2]` 와 같이 수식화 가능 여부 |
| 상태 저장소 | 계산된 해답을 보관하는 메모리 테이블 | 배열 또는 해시맵 할당 가능 공간 복잡도 제약 여부 |

> 요약: DP는 문제를 쪼갤 수 있어야 하며(최적부분구조), 쪼갠 조각들이 겹쳐서 재활용 가치가 있어야(중복부분문제) 성립된다.

---

## Ⅲ. 동작원리 및 하향식/상향식 적용 흐름도

```text
[방식 A: Top-Down] 큰 문제 호출 -> 쪼개며 재귀 하강 -> Base 연산 후 올라오며 캐시(Memoization) 저장
[방식 B: Bottom-Up] 인덱스 0(Base) 초기화 -> 반복문(For) 가동 -> 캐시(Tabulation) 앞칸 값으로 뒷칸 계산
```

| 기법 구분 | 처리 방식 (메커니즘) | 장단점 비교 |
|:---:|:---|:---|
| 하향식 (Top-Down) | 재귀 함수와 Memoization 배열 결합 | 직관적 코드 작성 가능, 호출 스택(Call Stack) 오버플로우 위험 |
| 상향식 (Bottom-Up) | 배열 초기화 후 For 반복문 Tabulation 진행 | 함수 오버헤드 없음, 배열 공간 전체 강제 할당 오버헤드 발생 |

> 요약: 실무 최적화는 스택 프레임 생성 부하가 없고 OOM 예측이 쉬운 상향식(Bottom-Up) 반복문 구현을 표준으로 삼는다.

## Ⅳ. 특징

| 구분 | 배열(Array) 기반 캐시 | 해시맵(Hash Map) 기반 캐시 | 판단 포인트 |
|:---|:---|:---|:---|
| 상태 접근 속도 | 인덱스 직접 접근 O(1), 캐시 지역성 우수 | 해시 연산 오버헤드가 있는 평균 O(1) | 상태 공간의 조밀도 |
| 메모리 사용 | 가능한 상태 전체에 대해 사전 할당 필요 | 실제로 방문한 상태만 저장 | 상태 공간 크기 대비 실사용 비율 |
| 적용 상태 유형 | 정수 인덱스 등 조밀한(dense) 상태 공간 | 문자열·좌표쌍 등 희소(sparse)하거나 비정수 상태 공간 | 상태를 배열 인덱스로 정규화 가능 여부 |
| 대표 사례 | 피보나치, 0-1 배낭 문제(정수 인덱스) | 상태가 좌표쌍·문자열 조합인 그래프 탐색형 DP | 상태 표현 형태 |

> 요약: 상태가 정수 인덱스로 조밀하게 정규화되면 배열 캐시가 유리하고, 상태 공간이 희소하거나 비정수형이면 해시맵 캐시로 메모리를 절약한다.

## Ⅴ. 주요 알고리즘 패러다임 심화 비교

| 비교 축 | 동적 프로그래밍 (DP) | 분할 정복 (Divide & Conquer) | 탐욕 알고리즘 (Greedy) |
|:---|:---|:---|:---|
| 하위 문제 중복성 | 중복됨 (Overlapping) | 완전히 독립적 (독립 분할) | 중복 없음 (매 순간 확정) |
| 탐색 범위 | 모든 미래 경우의 수를 저장/비교 | - (중복 계산 없음) | 현재 시점 가장 좋은 것만 선택 |
| 대표 적용 | 플로이드 워셜, 0-1 배낭 문제 | 퀵/병합 정렬, 이진 탐색 | 다익스트라, 크루스칼 MST |
| 속도 vs 정확도 | 다소 느림 / 100% 글로벌 최적해 | (독립 분리 처리 특화) | 빠름 / 특정 조건 아니면 최적해 실패 |

> 요약: DP는 모든 가능성을 다 따져보되 겹치는 연산만 캐시로 스킵하여 그리디보다 정확하고 일반 재귀보다 빠른 교환점이다.

| 리스크 | 발생 원인 | 대응 기법 (메모리 최적화) | 확인 지표 |
|:---|:---|:---|:---|
| 2차원 DP 배열 OOM | 10만x10만 그리드 DP 설계 시 RAM 수 GB 할당 필요 | 1차원 배열 슬라이딩 윈도우로 덮어쓰기 (공간 축소 기법) | OS 할당 Heap 여유량 |
| 상태 폭발 (Explosion) | 상태 전이가 비트마스킹을 요할 정도로 복잡함 | 가지치기(Branch & Bound)를 휴리스틱하게 결합 | 2^N 공간 인덱스 포화도 |

> 요약: DP의 실무 리스크는 정확도가 아니라 메모리이므로, 차원 축소(슬라이딩 윈도우)와 가지치기로 공간 복잡도를 통제해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 시계열 데이터 시퀀스 매칭 (LCS/DTW): 두 염기 서열 혹은 음성 파형의 가장 긴 공통 문자열을 2차원 DP 점화식으로 밀리초 내 비교 분석
2. MSA 라우팅 (Floyd-Warshall): 노드 개수가 적은 통신망에서 N:N 라우터 간 최단 전송 테이블을 DP 기반 인접 행렬로 한 번에 산출하여 캐싱
3. 클라우드 리소스 할당 (0-1 Knapsack): 인스턴스의 제한된 CPU/RAM 내에서 최고 가치를 창출하는 컨테이너 조합을 DP로 역산하여 스케줄링

**결론 (2줄):**
- 기술사 판단: DP는 무모한 재귀 탐색을 '상태 저장(캐싱) 기반'의 유향 비순환 그래프(DAG) 구조로 변환시켜 지수 시간을 다항 시간으로 꺾는 설계의 정수이다.
- 향후 방향: 최근 강화학습 모델(MDP 기반 큐러닝 등)은 본질적으로 벨만 방정식이라는 DP 점화식을 기반으로 상태 가치를 업데이트하며 AI의 뼈대가 되고 있다.
