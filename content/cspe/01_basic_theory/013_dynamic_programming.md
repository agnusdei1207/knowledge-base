## 미리 알고가기

- 최적 부분 구조: 큰 문제의 최적해가 작은 문제 최적해로 구성되는 성질임
- 중복 부분 문제: 같은 부분 문제가 반복 계산되는 특성임
- 메모이제이션: 계산 결과를 저장해 재사용하는 방식임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 최적 부분 구조와 중복 부분 문제를 가진 문제를 작은 상태로 분해하고, 계산 결과를 저장해 재사용함으로써 전체 연산량을 줄이는 설계 기법임
- **배경/필요성**: 단순 재귀나 완전 탐색은 동일 계산을 반복해 지수 시간으로 폭증하므로, 상태를 정의하고 기억하는 방식이 실용적 해법이 됨

## Ⅱ. 특징

- 문제를 상태와 상태 전이로 바꿔 계산하므로 반복 계산 관계가 명확해짐
- 한 번 계산한 값을 저장해 같은 계산이 다시 발생하지 않게 함
- 하향식 메모이제이션과 상향식 타뷸레이션 중 구현 전략을 선택할 수 있음
- 상태 정의가 잘못되면 저장을 해도 효과가 없으므로 성능의 출발점은 상태 설계임

## Ⅲ. 종류 및 비교

| 판단 기준 | 동적 프로그래밍 | 분할 정복 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 중복됨 | 독립적임 | 단계별 선택 중심 |
| 결과 저장 | 반드시 필요 | 보통 없음 | 최소화됨 |
| 정답 보장 | 상태 정의가 맞으면 보장 | 문제 구조에 따라 보장 | 조건 성립 시만 보장 |
| 대표 강점 | 지수 시간 절감 | 병렬 분할 용이 | 빠른 결정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 | 문제를 구별하는 인덱스, 위치, 용량, 길이 같은 정보임. 정보가 부족하면 오답이 되고, 너무 많으면 상태 수가 폭증함 |
| 전이식 | 이전 상태에서 현재 상태 값을 계산하는 규칙임. 전이식이 틀리면 저장소가 있어도 잘못된 값이 누적됨 |
| 초기값 | 더 쪼갤 수 없는 가장 작은 문제의 답임. 초기값이 틀리면 이후 모든 상태가 틀어짐 |
| 저장소 | 계산한 상태 값을 보관하는 배열, 맵, 비트마스크 구조임. 크기와 접근 방식이 시간·메모리 비용을 결정함 |

```text
+---------+     +-----------+     +-----------+     +-----------+
| 초기값    | --> | 상태 정의    | --> | 전이식      | --> | 저장소 갱신  |
+---------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상태정의 | --> | 전이설계 | --> | 값저장 | --> | 답도출 |
+----------+     +----------+     +----------+     +----------+
```

1. **상태정의**: 문제를 구별하는 최소 정보 집합을 정함
2. **전이설계**: 현재 답이 어떤 이전 상태들로부터 오는지 정의함
3. **값저장**: 계산된 상태 값을 테이블이나 캐시에 저장함
4. **답도출**: 목표 상태의 값을 읽거나 최종 집계를 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 상태 차원을 불필요하게 늘리면 시간과 메모리가 함께 폭증함
   - 해결방안: 정말 필요한 정보만 상태에 남기고 축소 가능성을 검토한 뒤 상태 수, 메모리 사용량으로 검증함
2. 문제: 전이식은 맞지만 초기값이 틀려 경계 조건 오류로 전체 결과가 왜곡됨
   - 해결방안: 가장 작은 입력 사례부터 손으로 확인하고 base case 테스트로 검증함
3. 문제: 재귀 기반 구현에서 호출 부하가 커 메모이제이션을 써도 깊은 호출이 부담이 될 수 있음
   - 해결방안: 반복문 기반 타뷸레이션으로 전환하고 호출 깊이, 실행시간으로 검증함

## Ⅶ. 적용 사례

- 문자열 유사도 계산에서는 편집 거리나 LCS를 상태 전이로 계산하며, 계산 시간과 테이블 크기로 결과를 확인함
- 자원 배분에서는 배낭 문제 계열에서 제한 용량 기준 최적값을 계산하며, 최적값 정확도와 메모리 사용량으로 결과를 확인함
- 경로 수 집계에서는 격자 이동이나 DAG 경로 수를 누적 계산하며, 상태 수와 처리량으로 결과를 확인함

## Ⅷ. 결론

동적 프로그래밍의 성패는 알고리즘 종류가 아니라 상태를 얼마나 정확하고 작게 정의하느냐에 달려 있음.
