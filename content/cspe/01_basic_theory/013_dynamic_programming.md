# 동적 프로그래밍 (Dynamic Programming)

## 미리 알고가기

- **점화식(recurrence relation)**: 지금 구할 답을 자기보다 작은 답들의 조합으로 적은 식. 예를 들어 피보나치는 `f(n) = f(n-1) + f(n-2)`처럼, 큰 답을 바로 아래 두 답을 더해 만든다.
- **메모이제이션(memoization)**: 한 번 계산한 작은 문제의 답을 표에 적어 두고, 같은 문제가 또 나오면 다시 풀지 않고 표에서 꺼내 쓰는 것. "이미 풀어 본 문제는 답만 베낀다"는 뜻이다.
- **중복 부분 문제**: 하나의 작은 문제가 여러 갈래에서 똑같이 다시 필요해지는 상황. 이게 있어야 답을 적어 두고 재사용하는 이득이 생긴다.
- **최적 부분 구조**: 큰 문제의 최적해가 작은 문제들의 최적해를 조립해서 만들어지는 성질. 이게 있어야 작은 답으로 큰 답을 정확히 세울 수 있다.

## 1. 개요

- **정의/개념**: 동적 프로그래밍(Dynamic Programming, DP)은 큰 문제를 작은 문제로 쪼갠 뒤, 한 번 푼 작은 문제의 답을 표에 저장했다가 같은 문제가 다시 나오면 계산 대신 꺼내 써서 최적값·경우의 수·가능 여부를 구하는 기법이다.
- **배경/필요성**: 문제를 작게 쪼개 푸는 분할정복은 쪼갠 조각들이 서로 겹치지 않을 때 잘 통한다. 그런데 `f(n) = f(n-1) + f(n-2)`처럼 쪼개면 `f(n-2)`가 양쪽 가지에서 똑같이 또 필요해지고, 이 겹치는 조각을 재귀가 매번 처음부터 다시 계산하면 계산량이 가지 수만큼 지수로 불어난다. 그렇다고 매 순간 눈앞의 최선만 집는 탐욕법은 빠르지만, 지금의 선택이 뒤를 망치는 문제에서는 틀린 답을 낸다. DP는 겹치는 작은 문제를 딱 한 번만 풀어 표에 적어 두고 재사용해, 지수로 불어나던 계산을 서로 다른 작은 문제의 개수만큼으로 눌러 준다.

DP는 아무 문제에나 쓰는 만능 기법이 아니라, 작은 문제가 겹쳐서 반복되고(중복 부분 문제) 그 작은 답들로 큰 답이 정확히 조립될 때(최적 부분 구조)만 힘을 낸다.

## 2. 특징 및 비교

같은 문제를 두고 세 방식은 "이미 푼 것을 기억하느냐"와 "선택을 되짚을 수 있느냐"에서 갈린다.

| 구분 | 단순 재귀 | 동적 프로그래밍 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 계산 방식 | 겹치는 문제를 매번 다시 풂 | 한 번 푼 답을 저장해 재사용 | 매 단계 눈앞의 최선만 선택 |
| 적용 조건 | 쪼개기만 되면 됨 | 중복 부분 문제 + 최적 부분 구조 | 탐욕 선택이 전체 최적을 보장할 때 |
| 정확성 | 맞지만 느릴 수 있음 | 점화식이 맞으면 최적 보장 | 성립 증명이 있어야 보장 |
| 비용 | 지수 시간까지 폭발 | 상태 수 × 전이 수에 비례 | 대체로 가장 가벼움 |

> 요약: 겹치는 작은 문제가 있고 되짚어야 최적이면 DP, 앞만 보고 집어도 맞으면 탐욕이다.

DP를 실제로 짜는 방식은 두 갈래다. 하나는 **Top-down(메모이제이션)**으로, 재귀를 그대로 두되 답을 처음 구할 때 표에 적어 두고 두 번째부터는 표에서 꺼낸다. 필요한 작은 문제만 골라 계산하지만 재귀 호출이 깊어지면 콜 스택이 부담이다. 다른 하나는 **Bottom-up(타뷸레이션)**으로, 가장 작은 문제부터 표를 차례로 채워 올라가 큰 문제에 도달한다. 재귀가 없어 빠르고 안전하지만, 채우는 순서를 사람이 정확히 정해야 한다.

DP를 쓸지, 어느 방식으로 짤지는 상태 수와 전이 수(계산량이 감당되는가), 표 크기(메모리에 올라가는가), 점화식을 작은 입력으로 검증할 수 있는가, 최적해를 값뿐 아니라 경로까지 복원해야 하는가로 판단한다.

## 3. 구성요소/구조

DP는 결국 "작은 답을 담을 표"와 "그 표를 채우는 규칙"으로 이루어진다.

| 구성요소 | 하는 일 | 왜 중요한가 |
|:---|:---|:---|
| 상태(State) | 작은 문제 하나를 가리키는 좌표(변수 묶음) | 문제의 제약과 목표를 빠짐없이 담아야 답이 뒤섞이지 않음 |
| 점화식 | 작은 상태들의 답으로 현재 상태의 답을 세우는 규칙 | 전이 조건이 어긋나면 표를 다 채워도 오답 |
| 초기값 | 더 쪼갤 수 없는 가장 작은 문제의 답 | 여기가 틀리면 위로 쌓인 값이 전부 오염됨 |
| 계산 순서 | 참조할 상태가 먼저 채워지도록 정한 순서 | 아직 안 채운 칸을 참조하면 계산이 깨짐 |
| 저장 테이블 | 상태별 답을 적어 두는 공간 | 시간을 아끼는 대신 메모리를 씀(트레이드오프) |

```text
상태 정의  ->  점화식 수립  ->  초기값 설정  ->  계산 순서 결정  ->  최종 상태 반환
 (좌표)       (칸 채우는 식)    (바닥 값)       (아래→위 방향)      (답 읽기)
```

예를 들어 피보나치는 상태가 `n` 하나, 점화식은 `f(n)=f(n-1)+f(n-2)`, 초기값은 `f(0)=0, f(1)=1`이다. 표 `f[0..n]`을 앞에서부터 채우면, 단순 재귀가 겹쳐 계산하던 `f(n-2)`를 표의 한 칸에서 한 번만 구해 재사용하므로 계산이 `n`번으로 줄어든다.

DP에서 생기는 문제는 대부분 이 다섯 중 하나, 즉 상태 정의·점화식·계산 순서 중 하나가 문제의 제약과 어긋날 때 터진다.

## 4. 문제점 및 개선방안

1. **상태 폭발**: 상태 변수를 늘릴수록 표 칸 수가 곱으로 불어나, 시간과 메모리가 감당 못 할 만큼 커진다.
   - **개선방안**: 최근 몇 줄만 남기는 상태 압축(rolling array), 희소 테이블(sparse table), 불가능한 상태를 쳐내는 가지치기, 절반씩 나눠 합치는 meet-in-the-middle을 적용한다. (확인: 표 크기, 상태 수)

2. **점화식 오류**: 상태가 문제의 제약을 다 담지 못하면, 표를 규칙대로 채워도 실제 정답이 되지 않는다.
   - **개선방안**: 작은 입력에서 완전탐색(브루트포스) 결과와 DP 결과를 대조해 불일치를 잡는다. (확인: 소규모 입력 전수 비교 일치율)

3. **계산 순서·초기값 오류**: 참조할 칸이 아직 안 채워졌거나 바닥 값이 틀리면, 그 위로 쌓인 답이 전부 오염된다.
   - **개선방안**: 초기값 표와 반복문 진행 방향을 명시하고, 경계 입력(빈 입력, 최소·최대값)으로 테스트한다. (확인: 경계 입력 출력 정확도)

## 5. 실무 적용 사례

| 적용 영역 | 어떻게 쓰나 | 무엇으로 효과를 확인하나 |
|:---|:---|:---|
| 최적화 문제 | 배낭 문제·경로 최적화·자원 배분을 상태와 점화식으로 세워 최적값을 구함 | 최적값, 상태 수 대비 계산 시간 |
| 문자열 처리 | 편집 거리·LCS·시퀀스 정렬을 2차원 표로 채워 유사도를 계산 | 정확도, 테이블 크기 |
| 확률·추론 모델 | Viterbi로 은닉 마르코프 모델의 가장 그럴듯한 상태열을 복원 | 추론 시간, 메모리 사용량 |

> 요약: 최적값을 되짚어 찾거나(최적화), 두 열을 맞대 유사도를 재거나(문자열), 가장 그럴듯한 경로를 고를 때(추론) DP가 쓰인다.

## 6. 결론

동적 프로그래밍은 겹쳐서 반복되던 계산을 한 번만 풀어 표에 적어 두는 방식으로, 지수로 폭발하던 재귀를 상태 수에 비례하는 계산으로 바꾸는 기법이다. 핵심은 문제의 제약을 빠짐없이 담은 상태 정의와, 작은 답으로 큰 답을 정확히 세우는 점화식이며, 여기에 초기값·계산 순서·표 크기를 함께 관리해야 결과가 맞고 감당된다. 그래서 실무의 판단은 "재귀냐 DP냐"가 아니라, 작은 문제가 겹치는가, 그 답으로 최적이 조립되는가, 상태 수와 메모리가 버티는가를 보고 정하는 문제로 좁혀진다.
