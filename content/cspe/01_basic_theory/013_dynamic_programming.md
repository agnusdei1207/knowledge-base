# 013. 동적 프로그래밍 (Dynamic Programming)

## 미리 알고가기

- **점화식 (Recurrence Relation)**: 큰 문제의 답을 작은 문제의 답들을 이용하여 정의하는 수식임
- **메모이제이션 (Memoization)**: 동일한 계산을 반복해야 할 때, 이전에 계산한 값을 저장하여 재사용하는 기법임
- **최적 부분 구조 (Optimal Substructure)**: 큰 문제의 최적해가 작은 문제들의 최적해로 구성되는 성질임

## 1. 개요

- **정의/개념**: 동적 프로그래밍(Dynamic Programming, DP)은 복잡한 문제를 여러 개의 작은 부분 문제로 나누어 해결하고, 그 결과를 저장하여 중복 계산을 방지함으로써 효율성을 극대화하는 알고리즘 설계 기법임
- **배경/필요성**: 단순 재귀(Recursion)는 중복되는 부분 문제를 반복 계산하여 연산량이 지수적으로 증가함. 이를 해결하기 위해 '기억하며 풀기' 전략을 사용하여, 기하급수적인 연산 비용을 다항 시간(Polynomial Time) 내로 단축시키기 위해 사용함

## 2. 특징 및 비교

DP는 분할 정복과 유사하나 부분 문제의 중복 여부에서 차이가 있으며, 탐욕법과는 최적해 보장 방식에서 차별화됨.

| 비교 항목 | 동적 프로그래밍 (DP) | 분할 정복 (Divide & Conquer) | 탐욕 알고리즘 (Greedy) |
|:---|:---|:---|:---|
| **부분 문제 관계** | **중복 발생 (Overlapping)** | 서로 독립적 (Independent) | 해당 없음 (매 순간 최선 선택) |
| **최적해 보장** | 항상 보장 (전체 탐색 효과) | 항상 보장 | 특정 조건(Greedy Choice) 시 보장 |
| **메모리 사용** | **Memoization** 테이블 필요 | 상대적으로 적음 | 매우 적음 |
| **하향식/상향식** | 둘 다 가능 (Top-down, Bottom-up) | 주로 하향식 | 해당 없음 |
| **대표 예시** | LCS, Knapsack, 최단 경로 | 병합 정렬, 퀵 정렬 | 거스름돈, 최소 신장 트리 |

> 요약: 부분 문제가 겹치고 전체 최적해를 위해 과거의 선택을 고려해야 할 때 DP가 가장 강력함.

## 3. 구성요소/구조

DP의 성공적 구현은 문제의 상태를 정의하고 상태 간의 전이 관계(점화식)를 수립하는 과정에 달려 있음.

- **구성요소**:
  - **상태 (State)**: 문제를 정의하는 변수들의 집합 (예: $DP[i][j]$)
  - **점화식 (Transition)**: 이전 상태를 이용하여 현재 상태의 값을 도출하는 식
  - **초기 상태 (Base Case)**: 더 이상 쪼개지지 않는 가장 작은 문제의 해
  - **테이블 (Memo-table)**: 계산된 상태값을 저장하는 배열 또는 맵

- **구현 방식 비교 (원리/흐름도)**:

```text
[Top-down (Memoization)]             [Bottom-up (Tabulation)]
1. 큰 문제 호출                       1. 가장 작은 문제부터 시작
2. if (이미 계산됨) return 저장값      2. 루프를 돌며 테이블을 차례로 채움
3. else 계산 후 저장 & return         3. 최종 목표 상태에 도달
(재귀 구조 사용)                      (반복문 구조 사용)
```

1. **Top-down**: 위에서 아래로 내려가며 필요한 값만 계산함. 가독성이 좋으나 재귀 깊이(Stack) 제약이 있음
2. **Bottom-up**: 아래에서 위로 표를 채워나감. 재귀 오버헤드가 없고 성능이 안정적이나, 모든 상태를 계산해야 함

## 4. 문제점 및 개선방안

1. **메모리 사용량 과다 (공간 복잡도)**: 상태 변수가 많아질수록 테이블의 크기가 기하급수적으로 커져 메모리 부족을 유발함
   - **개선방안**: 현재 상태 계산에 필요한 직전 상태들만 유지하는 **슬라이딩 윈도우 (Sliding Window)** 기법이나 **공간 최적화 (Space Optimization)**를 통해 차원을 축소함 (확인: 메모리 점유율 분석)

2. **최적 부분 구조 위배**: 문제의 조건이 과거의 특정 선택에 종속적일 경우 단순한 점화식으로 해결할 수 없음
   - **개선방안**: 상태 정의에 과거의 선택 정보를 추가하거나(비트마스킹 등), 문제의 도메인 특성을 재분석하여 상태 전이를 재설계함 (확인: 부분 문제 독립성 검증)

3. **중복 없는 문제에 대한 오버헤드**: 부분 문제가 겹치지 않는 경우 테이블 생성 및 조회 비용이 오히려 단순 재귀보다 클 수 있음
   - **개선방안**: 문제의 특성을 분석하여 중복이 발생하지 않는다면 분할 정복이나 다른 최적화 기법을 적용함 (확인: 중복 부분 문제 발생 빈도)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 자원 할당 (Knapsack) | 한정된 예산/시간 내에서 가치를 극대화하는 프로젝트나 아이템 조합 선정 | 총 가치 합산, 자원 소모율 |
| 유전자 서열 분석 (LCS) | 두 염기서열 간의 가장 긴 공통 부분 수열을 찾아 유사성 판별 | 유사도 점수, 비교 소요 시간 |
| 텍스트 편집기 (Edit Distance) | 한 문자열을 다른 문자열로 바꾸는 최소 편집 연산(삽입, 삭제, 수정) 횟수 계산 | 오타 교정 정확도, 검색 추천 속도 |
| 금융 파생상품 가격 결정 | 이항 트리 모델 등을 통해 시간 흐름에 따른 옵션 가격의 최적값 도출 | 가격 산출 정확도, 계산 지연 |

> 요약: 정답이 하나가 아닌 최적의 값을 찾아야 하거나, 모든 경우를 따져야 하지만 효율이 필요한 문제에 전방위로 활용됨.

## 6. 결론

동적 프로그래밍은 '시간과 공간의 트레이드오프'를 극대화하여 지수 시간의 문제를 다항 시간으로 끌어내리는 가장 대표적인 알고리즘 설계 기법임. 기술사는 단순히 점화식을 세우는 것을 넘어, 문제의 제약 조건을 상태 변수로 어떻게 추상화할 것인지, 그리고 메모리 한계를 극복하기 위해 공간 최적화를 어떻게 적용할 것인지에 대한 설계적 통찰력을 갖추어야 함.

특히 현대의 실시간 대용량 시스템에서는 DP의 결과를 캐싱하거나, 분산 환경에서 부분 문제의 결과를 공유하는 등 시스템 아키텍처와 결합된 형태의 DP 최적화가 요구됨. 결국 DP는 복잡한 현실 세계의 문제를 정형화된 수식으로 치환하여 효율적으로 해결하는 '구조적 사고'의 결정체임.
