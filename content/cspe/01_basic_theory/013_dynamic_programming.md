# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 복잡한 문제를 여러 개의 작은 하위 문제로 나누어 풀고, 그 결괏값을 저장하여 다시 똑같은 문제가 나올 때 재사용하는 알고리즘 최적화 기법이다.
- **왜 필요한가**: 똑같은 연산을 수백만 번 반복해야 하는 순수 재귀 방식의 비효율성을 캐시(저장소)를 통해 획기적으로 제거하기 위함이다.
- **핵심 직관**: "기억하며 풀기". 한 번 답을 구한 문제는 장부에 적어두고, 나중에 그 문제가 또 나오면 계산하지 않고 장부에서 답만 쓱 꺼내 쓴다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 최적 부분 구조 (Optimal Substructure) | 작은 문제의 최적해를 합치면 큰 문제의 최적해가 되는 성질 | 서울-대전 최단거리 + 대전-부산 최단거리 = 서울-부산 최단거리 |
| 중복 부분 문제 (Overlapping) | 동일한 하위 문제가 재귀 과정에서 여러 번 반복 호출되는 성질 | 수학 문제집에서 똑같은 15번 문제를 계속 처음부터 다시 푸는 상황 |
| 메모이제이션 (Memoization) | 위에서 아래로(Top-Down) 풀면서 결괏값을 메모리에 기록해 나가는 방식 | 방학 숙제를 나중에 필요할 때마다 빈칸 채우기 |
| 타뷸레이션 (Tabulation) | 아래에서 위로(Bottom-Up) 풀면서 표(Table)를 처음부터 꽉 채워나가는 방식 | 구구단을 1단부터 9단까지 순서대로 표 전부 채우기 |

## 깊이 이해
- **배경·문제의식**: 피보나치 수열 `F(n) = F(n-1) + F(n-2)`를 순수 재귀로 풀면 `F(2)` 같은 작은 단위를 계속 반복 계산하므로 O(2^n)의 지수 시간이 걸려 컴퓨터가 뻗는다.
- **작동 원리**: 이 기법을 쓰려면 문제 구조가 '중복 부분 문제'와 '최적 부분 구조' 2대 조건을 반드시 만족해야 한다. 조건 통과 후 부분 결과를 저장할 배열(캐시)을 만들고, 재귀(Top-Down)나 반복문(Bottom-Up)으로 값을 채운다.
- **비유**: 100번째 방문자를 셀 때, 1번부터 100번까지 손가락으로 다 세는 것(순수 재귀)이 아니라, 99번째 방문자가 벽에 적어둔 "99명"이라는 숫자를 보고 "+1"만 덧셈하는 것(DP)이다.
- **구체 예시**: 피보나치 수를 DP로 풀면 배열에 값을 한 번만 기록하므로 O(N)으로 극적으로 빨라진다. 배낭 문제(Knapsack), 최단 경로(플로이드-워셜) 등 조합 최적화에 널리 쓰인다.
- **흔한 오해·주의점**: 분할 정복(Divide & Conquer)과 자주 헷갈린다. 분할 정복은 쪼갠 문제들이 겹치지 않을 때(병합 정렬 등) 쓰고, DP는 쪼갠 문제들이 '서로 중복해서 겹칠 때' 재활용을 위해 쓴다.

## 연결 개념
- (014 분할 정복 참조) 부분 문제의 중복성 유무에 따른 차이 비교
- 최단 경로 플로이드-워셜 (DP를 응용한 다대다 탐색)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 하위 문제의 연산 결괏값을 메모리에 캐싱하여 재활용함으로써 연산 중복을 배제하는 최적화 기법.
> 2. **가치**: 지수 시간 O(2^n)이 소요되는 복합 순열/조합 문제를 다항 시간 O(N^2) 단위로 획기적으로 단축.
> 3. **판단 포인트**: 문제 구조가 최적 부분 구조(Optimal Substructure)와 중복 부분 문제(Overlapping)를 충족하는지 사전 판별이 필수.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 적용 필수 전제조건 증명 | 최적 부분 구조, 중복 부분 문제 만족 여부 식별 | 캐싱(Memoization)만 설명하고 성립 조건 누락 |
| 구현 메커니즘의 차이 비교 판단 | Top-Down(하향식) vs Bottom-Up(상향식) 성능 대조 | 타 패러다임(분할 정복, 탐욕법)과의 목적 차이 누락 |

> 요약: DP 성립 2대 조건을 명시하고, 중복 연산 제거를 위한 상향식/하향식 메모리 통제 기법을 명확히 대조해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 복잡한 문제를 중복되는 하위 문제로 분할하고, 계산된 최적해를 저장 및 재사용해 연산 복잡도를 줄이는 알고리즘
- 배경: 피보나치 등 점화식 문제를 단순 재귀 호출 시 O(2^n)의 중복 함수 호출로 시스템 스택 오버플로우 초래
- 필요성: 네트워크 최적 라우팅, 클라우드 자원 할당 등 조합 최적화 문제에서 O(N) 이내의 고속 연산 스루풋 필요

---

## Ⅱ. 구조 및 구성요소

```text
[입력 문제] -> [성립 조건 검증] -> [상태 정의 및 점화식 도출] -> [캐싱/표 채우기] -> [최종 해 산출]
                  |
                  +-> 최적 부분 구조 / 중복 부분 문제
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 점화식 (Recurrence Relation) | 현재 상태와 이전 상태 간의 수학적 관계 및 전이 규칙 정의 | `dp[i] = dp[i-1] + dp[i-2]` 등 공식 도출 |
| DP 테이블 (Cache Table) | 연산된 하위 문제의 결과(최적해)를 저장하는 메모리 공간 | 1~2차원 배열 사용 시 공간 복잡도 트레이드오프 발생 |
| 기저 조건 (Base Case) | 재귀 및 반복이 종료되는 가장 작은 독립 하위 문제의 초기값 | `dp[0]=0, dp[1]=1` 등 예외 없는 탈출 조건 세팅 |

> 요약: 성립 조건을 통과한 문제를 점화식으로 규정하고, 계산된 값을 DP 테이블에 기록하여 중복 호출을 원천 차단한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 분할 -> 기저 조건(Base Case) 초기화 -> 점화식 기반 값 평가 -> 결과 캐싱(Memoization) -> O(1) 리턴
```

- 1단계 [문제 검증 및 분할]: 전체 문제를 하위로 쪼개고, 중복 연산과 최적 부분 구조 발생 여부를 확인
- 2단계 [초기값 할당 및 배열 생성]: 메모리를 할당하여 DP 테이블을 만들고 기저 조건(가장 작은 답)을 배열에 주입
- 3단계 [점화식 순차 연산]: Top-Down(재귀 탐색) 또는 Bottom-Up(반복문) 방식으로 미계산 상태의 값을 수식 연산
- 4단계 [캐싱 및 재사용]: 연산 결과를 배열에 즉시 기록하며, 동일 인자 호출 시 연산을 생략하고 O(1)로 캐시 반환

> 요약: 최초 접근 시 값을 구하여 캐시에 기록해 두고, 이후 같은 문제에 봉착하면 캐시 값을 즉시 반환하여 수행 시간을 깎는다.

---

## Ⅳ. 특징
- 연산 폭 축소: O(2^n) 형태의 거대한 재귀 호출 트리를 가지치기(Pruning)하여 O(N) 선형 수준으로 시간 복잡도 혁신
- 메모리 트레이드오프: 계산 결과를 유지하기 위한 캐시 배열 공간을 상시 점유하므로, 시간 단축과 메모리 사용의 치환 발생
- 추상적 설계 난이도: 문제의 맥락 안에서 상태 배열 `dp[]`가 의미하는 바를 정의하고 점화식을 찾아내는 수학적 모델링 역량 필수

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | DP - Top Down (하향식) | DP - Bottom Up (상향식) | 선택 기준 |
|:---|:---|:---|:---|
| 접근 방향 | 큰 문제에서 시작해 필요한 하위로만 재귀 호출 | 가장 작은 문제부터 순차적 반복문으로 쌓아 올림 | 호출 스택 여유 및 함수 비용 |
| 구현 코어 | Memoization(메모이제이션) + 재귀 함수 | Tabulation(타뷸레이션) + for 루프 | 상태 의존성의 선형 순서 여부 |
| 성능 특성 | 실제 방문이 필요한 상태만 골라내어 제한적 계산 | 정의된 DP 테이블 전체 배열을 순차적으로 꽉 채움 | 하위 문제 도출의 밀집/희소 비율 |

> 요약: 호출해야 할 하위 상태가 듬성듬성하다면 재귀 기반 Top-Down이 유리하고, 모든 상태를 다 채워야 한다면 함수 오버헤드가 없는 Bottom-Up이 빠르다.

**리스크·대응:**
- 콜 스택 오버플로우: Top-Down 재귀에서 N이 수만을 넘길 경우 발생 → 깊이 제한(`sys.setrecursionlimit`) 상향 조정 또는 Bottom-Up 반복문 아키텍처로 전면 재설계
- 2차원 배열 메모리 폭발: 상태 유지를 위해 O(N^2) 부하 유발 → 직전 단계 2~3개의 상태만 필요한 경우 슬라이딩 윈도우(배열 재활용) 기법으로 O(1) 수준 압축 변환

**도입 후 점검 지표:**
- 캐시 히트율(Cache Hit Ratio): 순수 재귀 호출 수 대비 DP 적용 후의 히트율이 90% 이상인지 모니터링하여 중복 최적화 입증
- 공간 허용치: 할당된 DP 테이블 공간이 시스템 가용 Heap 메모리 한도(예: 256MB) 내에 안정적으로 수용되는지 프로파일링

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 배낭 문제(Knapsack) 자원 스케줄링: 허용된 용량(자원) 내에서 가치를 극대화하는 투자 조합을 도출하여 클라우드 VM 포트폴리오 최적화에 적용
2. 텍스트 유사도 판별(LCS): 버전 관리(Git) Diff 엔진 및 생물학 DNA 서열 분석 시, 두 문자열의 최장 공통 부분 수열을 도출해 변경점 트래킹
3. 다대다 최단 경로 도출: 라우팅 플로이드-워셜 기법 적용 시 노드 간 중간 경유지 상태를 DP 테이블에 점진적으로 갱신하여 전체 망 통신 최적화

**결론:**
- 기술사 판단: DP는 다항 시간 단축의 핵심 솔루션이나, 적용 전 '최적 부분 구조' 성립 여부를 엄격히 검증하지 않고 맹목적으로 테이블화할 경우 잘못된 로컬 최적해를 정답으로 내놓을 위험이 크다.
- 향후 방향: 단순 코딩 테스트를 넘어 최근 AI 강화학습(마르코프 결정 과정)의 상태 가치함수 평가 엔진 기저에 DP 원리가 쓰이므로, AI 인프라 최적화 지식으로 확장이 요구된다.
