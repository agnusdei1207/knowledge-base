## 미리 알고가기

- 중복 부분 문제(Overlapping Subproblems): 큰 문제를 해결하기 위해 계산한 작은 문제의 답이 반복적으로 다시 나타나는 성질임
- 최적 부분 구조(Optimal Substructure): 작은 문제들의 최적해를 조합하면 큰 문제의 최적해를 구할 수 있는 성질임
- 메모이제이션(Memoization): 하향식(Top-down) 접근에서 계산한 부분 문제의 답을 캐시에 저장하여 중복 계산을 방지하는 기법임
- 타뷸레이션(Tabulation): 상향식(Bottom-up) 접근에서 작은 문제부터 순서대로 답을 채워나가며 최종 해를 구하는 기법임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 복잡한 큰 문제를 더 작은 상태 단위의 부분 문제로 나누고, 각 부분 문제의 답을 메모리에 저장하여 동일한 계산의 반복을 차단하는 알고리즘 설계 기법임
- **배경/필요성**: 단순 재귀나 완전 탐색은 동일한 부분 문제를 기하급수적으로 반복 수행하여 응답 성능이 급격히 저하되므로, 계산 결과를 재사용($Reuse$)하여 처리 속도를 극적으로 높일 수 있는 최적화 체계가 필요함

## Ⅱ. 특징

- 분할 정복과 달리 부분 문제들이 서로 독립적이지 않고 중복되는 특성을 가지며, 이를 저장소($DP$ $Table$)에 기록함으로써 지수 시간의 연산을 다항 시간으로 감축함
- 상태를 정의하는 변수의 개수와 범위에 따라 공간 복잡도가 결정되므로, 메모리 사용량과 시간 효율성 간의 상충 관계를 고려한 상태 설계가 필수적임
- 한 단계의 최적화된 결과가 다음 단계의 입력이 되는 연쇄적 의존성을 가지며, 최종 단계의 값이 전체 문제의 최적해가 됨을 보장함

## Ⅲ. 종류 및 비교

| 판단 기준 | 하향식 ($Top-down$) | 상향식 ($Bottom-up$) |
|:---|:---|:---|
| **핵심 기법** | 메모이제이션 ($Memoization$) | 타뷸레이션 ($Tabulation$) |
| **수행 방식** | 큰 문제부터 재귀적으로 호출 | 작은 문제부터 반복문으로 누적 |
| **장점** | 필요한 부분 문제만 계산하여 효율적임 | 재귀 오버헤드가 없고 스택 관리가 용이함 |
| **단점** | 재귀 깊이가 깊어지면 스택 한계에 도달함 | 정답과 상관없는 모든 상태를 계산해야 함 |
| **대표 도구** | 재귀 함수, 해시/배열 캐시 | 반복문, $DP$ 테이블 (배열) |

> 요약: 직관적인 설계가 필요하면 하향식을, 시스템 안정성과 속도가 중요하면 상향식 접근법을 주로 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 ($State$) | 부분 문제를 유일하게 식별할 수 있는 변수(인덱스)들의 조합으로, 결과값을 담는 기준임 |
| 점화식 | 현재 상태의 값을 이전 상태들의 조합으로 산출하기 위한 수학적 관계식임 |
| 기저 사례 ($Base$ $Case$) | 더 이상 쪼갤 수 없는 가장 작은 규모의 문제에 대한 초기값(고정값)임 |
| 저장소 ($Memo/Table$) | 계산이 완료된 각 상태의 해를 보관하여 중복 호출 시 즉시 반환하는 메모리 공간임 |

```text
[ DP 프로세스 모델 ]
Step 1: 상태 정의 (f[i])
Step 2: 점화식 도출 (f[i] = f[i-1] + f[i-2])
Step 3: 초기값 설정 (f[0]=0, f[1]=1)
Step 4: 테이블 채우기 (Iteration or Recursion)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 문제 분할    | --> | 상태 및 점화식| --> | 초기값 설정   | --> | 최적해 상향식|
| (상태 정의)  |     | 수립 (관계)  |     | (기저 사례)  |     | 누적 (조합)  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **상태 정의** — 전체 문제를 해결하기 위해 필요한 최소한의 변수들을 추출하고, 부분 문제의 의미를 명확히 정의함
2. **점화식 수립** — 현재 단계의 최적해를 이전 단계의 최적해들로부터 도출하기 위한 논리적 인과 관계를 수식으로 작성함
3. **초기값 설정** — 점화식의 시작점이 되는 가장 작은 단위의 문제들에 대해 확정된 값을 저장소에 먼저 입력함
4. **해 누적** — 설정된 순서(상향식/하향식)에 따라 점화식을 적용하며 저장소를 채워나가고, 최종 목표 상태의 값을 추출함

## Ⅵ. 실무 적용 및 유의점

1. 상태를 너무 세분화하면 공간 복잡도가 기하급수적으로 늘어나는 '차원의 저주'가 발생할 수 있으므로, 상태 전이에 꼭 필요한 변수만 남기고 불필요한 차원은 제거하거나 슬라이딩 윈도우($Sliding$ $Window$) 기법으로 메모리를 절약해야 함
2. 점화식의 논리적 오류가 있으면 전체 결과가 왜곡되므로, 작은 규모의 예제 데이터를 통해 각 상태의 전이 과정이 최적 부분 구조를 만족하는지 검증하고 중복 계산이 완벽히 차단되는지 확인해야 함

## Ⅶ. 결론

- 동적 프로그래밍은 계산 자원의 낭비를 막고 알고리즘의 성능을 극대화하는 강력한 설계 도구이며, 설계자는 문제의 특성을 분석하여 점화식의 정확성과 메모리 효율성을 동시에 확보해야 함
