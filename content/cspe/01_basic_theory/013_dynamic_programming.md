# 📖 【암기용】 개념 완전 이해

> 목적: 동적 프로그래밍을 중복 계산 제거와 점화식 설계 관점으로 이해하게 만든다.

## 한눈에
- **개요**: 큰 문제를 겹치는 작은 문제로 나누고 결과를 저장해 재사용하는 알고리즘 설계 기법
- **왜 필요한가**: 재귀로 같은 하위 문제를 반복 계산하면 지수 시간이 되므로, 이미 구한 값을 저장해 계산량을 다항 시간으로 낮춤
- **핵심 직관**: 한 번 푼 문제의 답을 표에 적어두고, 다음에는 표를 조회함

## 깊이 이해
- **배경·문제의식**: 피보나치 재귀는 F(n-1), F(n-2)를 계속 다시 호출해 중복 호출이 폭증함. DP는 memoization 또는 tabulation으로 중복을 제거함
- **작동 원리**: ① 상태 정의, ② 점화식 도출, ③ 초기값 설정, ④ 계산 순서 결정, ⑤ 결과 추출 순서로 설계함
- **비유**: 같은 계산 문제를 여러 번 묻는 시험에서 답안지를 보관해 두고, 같은 문제가 나오면 다시 풀지 않고 확인하는 방식임
- **구체 예시**: Fibonacci는 단순 재귀 O(2^n)이나 DP 배열 사용 시 O(n) 시간, O(n) 공간이며 변수 2개만 쓰면 O(1) 공간으로 축소 가능
- **흔한 오해·주의점**: 모든 분할 문제가 DP는 아님. 하위 문제가 겹치지 않으면 분할 정복이고, 최적 부분 구조와 중복 부분 문제가 있어야 DP임

## 연결 개념
- 분할 정복 — 하위 문제가 독립이면 분할 정복, 중복되면 DP 검토
- 최단 경로 — 플로이드-워셜은 `dist[i][j][k]` 점화식 기반
- 최적화 문제 — 배낭 문제, 편집 거리, LCS의 대표 설계 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 동적 프로그래밍은 중복 부분 문제와 최적 부분 구조를 이용해 하위 문제 결과를 저장·재사용하는 설계 기법이다.
> 2. **가치**: 지수 시간 재귀를 O(n), O(nm), O(V^3) 같은 다항 시간으로 변환해 계산 가능 범위를 넓힌다.
> 3. **판단 포인트**: 상태 정의, 점화식, 초기값, 계산 순서, 공간 축소 가능성을 함께 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

개요: DP는 중복 계산을 저장해 재사용한다. 재귀 탐색은 같은 하위 문제를 반복 호출해 계산량이 급증한다. DP는 상태와 점화식을 명확히 정의해 최적화, 문자열, 그래프 문제의 계산량을 통제한다.

---

## Ⅱ. 구조 및 구성요소

```text
Problem -> State Definition -> Recurrence -> DP Table -> Answer
          / State: index and dimension
          / Recurrence: previous states
          / Storage: memoization or tabulation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 상태(State) | 하위 문제를 식별 | `dp[i][j]`처럼 인덱스 차원 정의 |
| 점화식(Recurrence) | 이전 상태로 현재 상태 계산 | 최적 부분 구조 반영 |
| 초기값(Base Case) | 계산 시작점 제공 | 경계 조건 누락 시 오류 |
| 저장 방식 | Memoization 또는 Tabulation | Top-down vs Bottom-up |

> 요약: DP는 상태·점화식·초기값·저장 방식이 맞물려 중복 하위 문제를 한 번만 계산한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
상태 정의 -> 초기값 설정 -> 계산 순서 결정 -> 점화식 적용 -> 답 추출/공간 축소
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 상태 변수와 차원 정의 | 모든 입력 조건 표현 가능 |
| 2 | 초기값과 경계 조건 설정 | 빈 문자열, i=0, j=0 처리 |
| 3 | 점화식으로 테이블 채움 | 이전 상태가 먼저 계산됨 |
| 4 | 결과 위치와 공간 축소 검토 | `dp[n]`, `dp[n][m]`, rolling array |

> 요약: DP의 성공 여부는 코드보다 상태 표현과 계산 순서가 점화식 의존성을 만족하는지에 달려 있다.

---

## Ⅳ. 특징

| 구분 | 단순 재귀 | 동적 프로그래밍 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 계산 방식 | 같은 하위 문제 반복 호출 | 하위 문제 결과 저장 | 호출 수 감소 |
| 시간복잡도 | Fibonacci O(2^n) | Fibonacci O(n) | 중복 상태 수 |
| 공간복잡도 | 콜스택 중심 | DP 테이블 사용 | O(n), O(nm), rolling O(1) |
| 적용 조건 | 중복 없어도 가능 | 중복 부분 문제 + 최적 부분 구조 | 배낭, LCS, 편집 거리 |

> 요약: DP는 저장 공간을 사용해 중복 호출을 제거하고, 상태 수와 전이 수의 곱으로 시간복잡도를 산정한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단순 재귀/분할정복 | 동적 프로그래밍 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 하위 문제 반복 계산 | 상태 결과 저장·재사용 | 중복 부분 문제 존재 시 |
| 비용/성능 | Fibonacci O(2^n) | Fibonacci O(n) | 상태 수 x 전이 수 산정 가능 |
| 운영/위험 | 구현 단순 | 상태 차원 증가와 메모리 증가 | 3차원 이상은 메모리 상한 검증 |

> 요약: DP는 중복 상태를 저장해 시간을 줄이지만 상태 차원과 메모리 예산을 먼저 계산해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 상태 폭발 | 상태 변수 과다 | 상태 압축, rolling array, pruning | DP table cell count |
| 점화식 오류 | 의존 상태 누락 | 작은 입력 brute force와 대조 | golden test 일치율 |
| 메모리 초과 | O(nm) 테이블 과대 | bitset, sparse map, rolling O(W) | peak RSS |

> 요약: DP 리스크는 상태 수, 점화식, 메모리이며 작은 입력 검증과 peak RSS로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 상태 정의 | 모든 입력 조건을 상태로 표현 | 설계 리뷰 |
| 복잡도 | 시간 = 상태 수 x 전이 수 명시 | 코드·문서 검토 |
| 정확도 | brute force 대비 결과 100% 일치 | 단위 테스트 |

> 요약: DP 성공 기준은 상태 완전성, 복잡도 명시, 작은 입력 정답 대조이다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 문자열 비교: 편집 거리 `dp[i][j]`로 삽입·삭제·치환 비용 계산, 문서 유사도와 데이터 정합성 검증에 적용
2. 자원 배분: 0/1 배낭 `dp[i][w]`로 예산 W 내 가치 최대 조합 산출, rolling array로 공간 O(nW)에서 O(W)로 축소
3. 그래프 분석: 플로이드-워셜 `dist[i][j]=min(dist[i][j], dist[i][k]+dist[k][j])`로 모든 쌍 비용 행렬 계산

**결론 (2줄):**
- 기술사 판단: 중복 부분 문제와 최적 부분 구조가 확인되면 DP를 적용하고, 상태 차원이 3개 이상이면 공간·시간 상한을 먼저 검증함
- 향후 방향: 대규모 DP는 bitset, rolling array, pruning, GPU 병렬 전이로 메모리 사용량과 전이 횟수를 제한해야 함
