# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 복잡한 문제를 여러 개의 작은 부분 문제(Subproblem)로 나누어 풀고, 그 **결과를 저장(Memoization)**하여 다시 계산하지 않음으로써 효율을 극대화하는 알고리즘 설계 기법.
- **핵심 2대 요건**:
  1. **최적 부분 구조 (Optimal Substructure)**: 작은 문제의 최적해를 결합하면 전체 문제의 최적해가 됨.
  2. **중복 부분 문제 (Overlapping Subproblems)**: 동일한 작은 문제가 반복적으로 나타남.
- **핵심 직관**: "한 번 푼 문제는 다시 풀지 않는다. 대신 장부(Table)에 적어둔다."

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **메모이제이션 (Memoization)** | 계산 결과를 배열/해시에 저장 (Top-Down) | 문제 풀고 정답지에 적어두기 |
| **타뷸레이션 (Tabulation)** | 작은 문제부터 순서대로 표를 채움 (Bottom-Up) | 1층부터 차례대로 벽돌 쌓기 |
| **점화식 (Recurrence)** | 큰 문제의 해를 작은 문제의 해로 나타낸 식 | 피보나치: $F(n) = F(n-1) + F(n-2)$ |
| **상태 (State)** | 문제를 식별할 수 있는 변수들의 집합 | "지금 가방에 $W$만큼 찼고 $i$번째 물건이다" |
| **상태 전이 (Transition)** | 한 상태에서 다음 상태로 넘어가는 규칙 | "물건을 넣을 것인가, 말 것인가?" |

## 깊이 이해

- **분할 정복(D&C) vs DP**: 
  - **분할 정복**: 큰 문제를 작게 나누지만, 나뉜 문제들이 서로 **독립적**입니다. (예: 퀵 정렬)
  - **DP**: 나뉜 문제들이 서로 **겹칩니다(Overlapping)**. 중복 계산을 피하기 위해 저장(Memo)이 필수입니다.

- **0/1 배낭 문제 (0/1 Knapsack Problem)**:
  - 물건을 쪼갤 수 없을 때(0 아니면 1), 배낭의 용량 $W$와 물건의 가치 $V$를 이용해 가치의 합을 최대화하는 문제.
  - 점화식: `dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])`
  - $O(NW)$의 시간 복잡도로 해결 가능.

- **최장 공통 부분 수열 (LCS, Longest Common Subsequence)**:
  - 두 문자열 사이의 공통된 부분 수열 중 가장 긴 것을 찾는 문제. (Git Diff, 유전자 서열 분석에 활용)
  - 점화식: 문자가 같으면 `dp[i-1][j-1] + 1`, 다르면 `max(dp[i-1][j], dp[i][j-1])`.

- **행렬 곱셈 순서 (Matrix Chain Multiplication)**:
  - 행렬은 결합 법칙이 성립하므로 곱하는 순서에 따라 전체 연산 횟수가 극단적으로 차이 납니다. DP를 통해 **연산 횟수를 최소화**하는 최적의 괄호 위치를 찾습니다.

- **일상 비유 (시험 공부)**:
  - 1단원부터 10단원까지 공부할 때, 1단원의 내용을 완벽히 정리해 두면 2단원의 1단원 응용 문제는 다시 공부할 필요 없이 정리본(Memo)만 보면 되는 것과 같습니다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 부분 문제의 해를 저장하여 **지수 시간($O(2^n)$) 복잡도를 다항 시간($O(n^k)$)**으로 획기적으로 낮추는 최적화 설계 기법임.
> 2. **가치**: 배낭 문제, LCS, 최단 경로 등 복잡한 최적화 문제에서 **전역 최적해(Global Optimum)**를 반드시 보장함.
> 3. **전략**: 상태(State)를 정의하고 **점화식(Recurrence Relation)**을 도출하는 것이 핵심이며, 메모리 제약 시 **롤링 배열(Rolling Array)**로 공간 효율화 가능.

## Ⅰ. 효율적 재사용의 철학, 동적 프로그래밍(DP)의 개요
### 1. 정의
- 복잡한 문제를 작은 부분 문제로 나누고, 그 결과값을 테이블(Table)에 저장하여 반복 계산을 방지함으로써 전체 문제를 해결하는 방식.
### 2. 성립 요건 (DP vs Recursion)
- **중복 부분 문제 (Overlapping Subproblems)**: 동일한 계산이 반복적으로 발생해야 저장의 의미가 있음.
- **최적 부분 구조 (Optimal Substructure)**: 큰 문제의 최적해가 작은 문제들의 최적해로부터 도출되어야 함.

## Ⅱ. DP 구현 방식 비교 (Top-Down vs Bottom-Up)
| 구분 | 하향식 (Top-Down) | 상향식 (Bottom-Up) |
|:---:|:---|:---|
| **기법** | **메모이제이션 (Memoization)** | **타뷸레이션 (Tabulation)** |
| **구현** | 재귀 (Recursion) | 반복문 (Iteration) |
| **장점** | 점화식 그대로 구현 가능, 필요한 문제만 품 | 재귀 오버헤드 없음, 스택 오버플로 안전 |
| **단점** | 재귀 깊이(Depth) 제한 위험 | 모든 부분 문제를 다 풀어야 함 |
| **선택** | 직관적 설계 필요 시 | 성능 최적화 및 공간 효율 중시 시 |

## Ⅲ. 대표적인 DP 알고리즘 및 점화식
### 1. 0/1 배낭 문제 (0/1 Knapsack)
- $i$번째 물건까지 고려하고 무게가 $w$일 때 최대 가치 $dp[i][w]$.
- `dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])`.
### 2. 최장 공통 부분 수열 (LCS)
- 두 문자열 $A, B$의 공통 부분 중 가장 긴 것.
- `if (A[i]==B[j]) dp[i][j] = dp[i-1][j-1] + 1 else max(dp[i-1][j], dp[i][j-1])`.
### 3. 편집 거리 (Edit Distance)
- 문자열 $A$를 $B$로 바꾸는 최소 연산(삽입, 삭제, 수정) 횟수 계산.

## Ⅳ. DP와 다른 설계 패러다임 비교
| 항목 | 동적 프로그래밍 (DP) | 분할 정복 (D&C) | 탐욕 알고리즘 (Greedy) |
|:---:|:---|:---|:---|
| **부분 문제 관계** | **상호 의존 (Overlapping)** | 상호 독립 (Independent) | 해당 없음 |
| **최적해 보장** | 항상 보장 | 항상 보장 | **상황에 따라 다름** |
| **주요 기법** | 메모이제이션/타뷸레이션 | 재귀 호출 | 매 순간 최선(Local Opt) 선택 |
| **대표 사례** | 최단 경로(플로이드), 배낭 | 병합 정렬, 퀵 정렬 | 거스름돈, 최소 신장 트리 |

## Ⅴ. 기술사 관점의 성능 최적화 및 고려사항
### 1. 공간 복잡도 최적화: 롤링 배열 (Rolling Array)
- 점화식이 `dp[i-1]`의 값만 참조하는 경우, $N \times M$ 배열 대신 $2 \times M$ 배열만 사용하여 공간을 $O(1)$ 수준으로 절감.
### 2. 상태 정의의 중요성
- 상태 변수가 너무 많으면 **상태 폭발(State Explosion)** 발생. 비즈니스 로직을 분석하여 필수적인 변수만으로 상태를 간소화해야 함.
### 3. 리스크 대응
- DP는 최적해를 찾기 위해 모든 경우를 훑으므로, $N$과 $W$가 너무 크면 다항 시간 내에 처리가 불가능할 수 있음($Pseudo-polynomial$). 이 경우 근사 알고리즘이나 탐욕법 고려.

## Ⅵ. 기술사 관점의 결론: "지능적인 기억이 성능을 만든다"
- 동적 프로그래밍은 컴퓨터의 연산 능력과 **메모리(기억)**를 교환하여 성능을 비약적으로 향상시키는 전략적 도구임.
- 미래의 시스템 아키텍트는 분산 환경에서도 부분 문제의 독립성을 확보하고, **분산 캐시(Redis 등)**를 활용한 전역 메모이제이션을 통해 대규모 시스템의 복잡도를 제어해야 함.
