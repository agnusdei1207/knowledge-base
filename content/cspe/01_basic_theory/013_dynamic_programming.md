## 미리 알고가기

- 최적 부분 구조: 지도에서 최단 경로를 구할 때 전체 경로의 최단 거리가 그 경로에 포함된 구간들의 최단 거리로 이루어지는 것처럼, 큰 문제의 최적해가 작은 문제의 최적해들로 자연스럽게 이어지는 성질임
- 중복 부분 문제: 피보나치 수를 재귀로 구할 때 같은 항을 여러 경로에서 다시 계산하듯, 같은 부분 문제가 반복해서 나타나는 특성임
- 메모이제이션: 한 번 푼 문제의 답을 메모지에 적어두고 같은 문제가 다시 나오면 메모지만 보고 답하듯, 이미 계산한 결과를 저장해 같은 입력이 들어오면 다시 계산하지 않는 방식임
- 상태 전이: 오늘의 값을 어제와 그제의 값으로 계산하듯, 한 상태의 답을 이전 상태들의 답으로 계산하는 규칙임
- 탐욕적 선택 속성: 매 단계에서 지금 당장 가장 좋아 보이는 선택을 해도 전체 최적해에 도달하는 문제의 성질임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 큰 문제를 작은 상태들로 나눈 뒤 각 상태의 답을 한 번만 계산해 저장하고 재사용함으로써 전체 계산량을 줄이는 알고리즘 설계 기법임. 상태를 잇는 전이식과 가장 작은 문제의 초기값이 올바르게 정의되면, 작은 상태의 답을 순서대로 쌓아 전체 최적해를 구할 수 있음
- **배경/필요성**: 피보나치 수열이나 최단 경로처럼 큰 문제가 작은 부분 문제로 쪼개지는 경우, 단순 재귀나 완전 탐색은 같은 부분 문제를 여러 경로에서 다시 계산함. 예를 들어 피보나치 수를 재귀로만 구하면 시간복잡도가 $O(2^n)$까지 늘어나므로, 이미 구한 부분 문제의 답을 저장해 두고 재사용하는 절차가 필요함

## Ⅱ. 특징

- 상태와 전이 중심의 문제 표현은 계산이 어디서 반복되고 어떤 정보가 필요한지를 바로 드러냄
- 저장된 상태 값의 재사용은 같은 부분 문제를 다시 계산하지 않게 해 지수 시간 문제를 다항 시간으로 낮추는 핵심 근거임
- 구현 방식은 재귀와 캐시를 결합한 메모이제이션(하향식)과 반복문으로 아래서부터 테이블을 채우는 상향식 두 가지로 나뉘며, 입력 특성에 맞게 선택함
- 상태 설계는 성능과 정답성을 동시에 좌우함. 상태를 너무 넓게 잡으면 저장 비용이 폭증하고, 너무 좁게 잡으면 정답에 필요한 조건이 빠짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 동적 프로그래밍 | 분할 정복 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 같은 부분 문제가 여러 번 반복되어 저장 이점이 큼 | 하위 문제가 서로 독립적이어서 저장 없이도 분해가 가능함 | 각 단계에서 하나의 선택을 바로 확정하는 구조임 |
| 결과 저장 방식 | 상태 값을 테이블이나 캐시에 저장해 다시 사용함 | 보통 저장 없이 하위 문제를 풀고 결과만 결합함 | 이전 선택을 별도로 저장하지 않고 즉시 진행함 |
| 정답 보장 조건 | 상태와 전이식이 맞으면 최적해를 보장함 | 문제 구조가 분할과 결합에 맞으면 정답을 구함 | 탐욕적 선택 속성이 성립할 때만 최적해를 보장함 |
| 대표 장점 | 반복 계산을 줄여 큰 입력도 다룰 수 있게 함 | 구조가 단순하고 병렬화하기 쉬움 | 구현이 단순하고 의사결정 속도가 빠름 |

> 요약: 동적 프로그래밍은 부분 문제가 반복된다는 점이 핵심이며, 저장이 필요 없거나 즉시 선택이 가능한 문제와는 접근 자체가 다름

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 | 부분 문제를 구분하는 변수 조합임. 인덱스나 조건을 좁게 잡으면 저장 비용이 줄지만, 정답에 필요한 조건을 빠뜨리면 오답이 남음 |
| 점화식 | 상태 간 관계를 나타내는 식임. $dp[i] = f(dp[i-1], dp[i-2], \dots)$ 형태로 이전 상태들의 답을 현재 상태의 답으로 연결함 |
| 초기값(기저 상태) | 더 이상 쪼갤 수 없는 가장 작은 상태의 답임. 이 값이 틀리면 점화식을 따라 전체 저장소가 틀린 값으로 채워짐 |
| 저장소 | 상태별 답을 담는 배열이나 캐시임. 상향식은 전체 테이블을 순서대로 채우고, 하향식은 실제로 방문한 상태만 캐시에 남김 |

```text
+-----------+      +-----------+      +-----------+
| 상태 i    | ---> | 점화식    | ---> | 저장소[i] |
+-----------+      +-----------+      +-----------+
      ^                                     |
      |                                     v
      +---------- 이전 상태 값 참조 <--------+
```

> 요약: 상태와 점화식이 저장소 구조를 결정하고, 저장소는 다시 다음 상태의 점화식 계산에 재사용됨

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상태정의 | -->  | 점화식도출| -->  | 초기값설정| -->  | 순회/재귀|
+----------+     +----------+     +----------+     +----------+
                                                          |
                                                          v
                                                    +----------+
                                                    | 결과조회 |
                                                    +----------+
```

1. **상태 정의**: 부분 문제를 인덱스, 잔여 용량 등 어떤 변수로 표현할지 정함
2. **점화식 도출**: 정의한 상태를 이전 상태들의 답으로 계산하는 관계식을 세움
3. **초기값 설정**: 더 쪼갤 수 없는 기저 상태의 답을 확정함
4. **순회/재귀 계산**: 상향식은 작은 상태부터 저장소를 채우고, 하향식은 재귀 호출마다 캐시를 먼저 확인한 뒤 없을 때만 계산해 저장함
5. **결과 조회**: 목표 상태의 저장값을 반환함

## Ⅵ. 실무 적용 및 유의점

1. 배낭 문제처럼 아이템과 용량의 조합으로 상태를 잡는 자원 배분 문제는 저장소가 빠르게 커지므로 현재 계산에 필요한 이전 행만 남기고 나머지는 버리는 방식으로 압축하고 최대 메모리 사용량으로 확인함
2. 상태 수가 많은 문제를 하향식 재귀로 풀면 호출 깊이가 커져 시스템 한계를 넘을 수 있으므로 큰 입력은 상향식 테이블 채움으로 바꾸고 최대 재귀 깊이와 실행 시간으로 확인함

## Ⅶ. 결론

동적 프로그래밍은 부분 문제가 반복되고 상태와 점화식을 명확히 정의할 수 있는 문제에서 저장소로 중복 계산을 없애는 선택이며, 상태 폭이 커지면 저장소 압축이나 상향식 전환으로 대응해야 함.
