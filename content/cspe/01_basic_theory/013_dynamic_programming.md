## 미리 알고가기

- 중복 부분 문제: 같은 작은 문제가 여러 번 다시 나타나는 성질임
- 최적 부분 구조: 작은 문제의 최적해를 모아 큰 문제의 최적해를 만들 수 있는 성질임
- 상태: 부분 문제를 구분하는 변수 조합임
- 점화식: 이전 상태의 값으로 현재 상태의 값을 계산하는 규칙임
- 메모이제이션: 이미 계산한 값을 저장해 다시 쓰는 방식임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 큰 문제를 상태 단위의 작은 문제로 나누고, 각 상태의 답을 저장해 반복 계산을 줄이는 알고리즘 설계 기법임
- **배경/필요성**: 단순 재귀나 완전 탐색은 같은 부분 문제를 여러 번 풀 수 있음. 부분 문제의 답을 저장하면 계산량을 크게 줄일 수 있음

## Ⅱ. 특징

- 상태와 점화식으로 문제를 표현하므로 필요한 정보와 계산 순서가 분명해짐
- 같은 상태를 다시 계산하지 않아 지수 시간 탐색을 다항 시간으로 줄일 수 있음
- 하향식은 필요한 상태만 계산하고, 상향식은 작은 상태부터 순서대로 채움
- 상태를 너무 크게 잡으면 메모리가 커지고, 너무 작게 잡으면 정답에 필요한 조건이 빠짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 동적 프로그래밍 | 분할 정복 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 부분 문제 | 반복됨 | 서로 독립적임 | 단계별 선택으로 진행됨 |
| 저장 여부 | 상태 값을 저장함 | 보통 저장하지 않음 | 선택 결과만 누적함 |
| 정답 조건 | 상태와 점화식이 맞아야 함 | 분할과 결합이 맞아야 함 | 탐욕 선택이 항상 옳아야 함 |
| 대표 문제 | 배낭, 편집 거리 | 병합 정렬 | 허프만 코딩, MST |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 | 부분 문제를 식별하는 기준임 |
| 점화식 | 이전 상태에서 현재 상태를 계산하는 규칙임 |
| 초기값 | 더 이상 쪼갤 수 없는 가장 작은 상태의 답임 |
| 저장소 | 상태별 답을 담는 배열, 테이블, 캐시임 |

```text
+--------+     +--------+     +----------+
| 초기값 | --> | 점화식 | --> | 상태 저장 |
+--------+     +--------+     +----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 상태 정의 | --> | 점화식 작성 | --> | 초기값 설정 | --> | 테이블 계산 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 부분 문제를 구분할 상태를 정함
2. 상태 사이의 계산 관계를 점화식으로 표현함
3. 가장 작은 상태의 초기값을 정함
4. 저장소를 채우며 최종 상태의 답을 구함

## Ⅵ. 실무 적용 및 유의점

1. 상태 정의가 잘못되면 저장소를 채워도 오답이 나오므로, 상태가 정답에 필요한 조건을 모두 담는지 반례로 확인해야 함
2. 상태 수가 커지는 문제는 전체 테이블을 만들기 전에 메모리 사용량을 계산하고 필요하면 rolling array나 메모이제이션으로 줄여야 함

## Ⅶ. 결론

- 동적 프로그래밍은 반복되는 부분 문제를 저장으로 줄이는 기법이며, 상태 설계가 성능과 정답성을 동시에 결정함
