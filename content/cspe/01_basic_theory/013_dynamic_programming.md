## 미리 알고가기

- 부분 문제: 큰 문제를 구성하는 더 작은 문제이며, 같은 형태의 입력을 가짐
- 중복 부분 문제: 재귀 과정에서 동일한 부분 문제가 여러 번 다시 등장하는 성질임
- 최적 부분 구조: 전체 최적해가 부분 문제의 최적해로 구성되는 성질임
- 메모이제이션: 이미 계산한 결과를 저장해 재사용하는 top-down 방식임
- 테뷸레이션: 작은 상태부터 표를 채우는 bottom-up 방식임

## Ⅰ. 개요

동적 프로그래밍(DP)은 중복되는 부분 문제의 결과를 상태로 저장하고 재사용해 전체 문제의 최적값, 경우의 수, 가능 여부를 계산하는 알고리즘 설계 기법임. 최적 부분 구조와 중복 부분 문제가 있을 때 지수적 재귀 탐색을 다항 시간 또는 더 낮은 비용으로 줄이기 위해 사용함.

DP의 핵심은 “어떤 값을 상태로 둘 것인가”와 “상태 간 점화식을 어떻게 세울 것인가”임. 상태 정의가 틀리면 표를 아무리 채워도 문제의 제약과 목표를 반영하지 못함.

비유: 같은 계산을 반복해서 묻는 손님에게 매번 새로 계산하지 않고, 계산표에 적어 두었다가 다시 보여주는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘 설계 패턴 이해 확인 | 상태, 점화식, 초기값, 중복 부분 문제, 최적 부분 구조 | 단순 재귀와 혼동, 상태 정의 누락 |

> 요약: DP는 반복되는 부분 문제의 결과를 저장하고 점화식으로 연결해 큰 문제를 계산하는 설계 기법임.

## Ⅱ. 특징/비교

| 판단 기준 | 단순 재귀 | 동적 프로그래밍 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 계산 방식 | 같은 부분 문제를 반복 계산 | 상태 결과를 저장해 재사용 | 매 단계 국소 최선 선택 |
| 적용 조건 | 구조 설명은 쉬우나 비용 큼 | 중복 부분 문제와 최적 부분 구조 필요 | greedy-choice property 필요 |
| 정확성 근거 | 재귀 정의 | 점화식과 상태 포괄성 | 국소 선택의 전역 최적 증명 |
| 비용 특성 | 지수 시간으로 커질 수 있음 | 상태 수와 전이 수에 비례 | 보통 빠르나 적용 범위 제한 |
| 선택 기준 | 입력 작거나 개념 설명 | 최적화·계수·판정 문제 | DP보다 단순한 선택 증명 가능 |

> 요약: DP는 탐욕처럼 빠른 선택이 안전하지 않고, 단순 재귀처럼 반복 계산이 큰 문제에서 선택함.

- top-down은 필요한 상태만 계산해 구현이 직관적이고, bottom-up은 호출 오버헤드가 적고 순서 제어가 명확함
- 상태 수가 많아지면 시간과 메모리가 함께 증가하므로 상태 압축이 중요한 최적화가 됨
- DP는 최적값뿐 아니라 선택 경로를 저장하면 실제 해를 복원할 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 문제정의 | ---> | 상태정의 | ---> | 점화식   |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 초기값   |      | 계산순서 |      | 결과복원 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 상태 | 부분 문제를 구분하는 변수 조합이며 DP 표의 인덱스가 됨 | 계산표의 좌표 |
| 점화식 | 작은 상태의 결과로 큰 상태를 계산하는 관계식임 | 표 채우기 규칙 |
| 초기값 | 더 쪼갤 수 없는 기본 상태의 값이며 계산의 출발점임 | 첫 칸의 기준값 |
| 계산 순서 | 점화식이 참조하는 상태가 먼저 계산되도록 정한 순서임 | 표를 채우는 방향 |
| 결과 복원 | 최적값을 만든 선택 정보를 따라 실제 해를 구성함 | 정답 경로 추적 |

> 요약: DP는 상태, 점화식, 초기값, 계산 순서가 맞아야 표의 값이 문제의 해를 의미하는 구조임.

- 상태는 문제 제약을 충분히 담아야 하지만 불필요한 변수를 넣으면 상태 폭발이 발생함
- 점화식에는 최댓값, 최솟값, 합산, 논리 OR처럼 목표 함수가 명확히 들어가야 함
- 계산 순서가 잘못되면 아직 계산되지 않은 상태를 참조해 값이 틀어질 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 성질확인 | ---> | 상태설계 | ---> | 표계산   | ---> | 해반환   |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 중복/최적|      | 점화/초기|      | 순서/저장|      | 값/경로  |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 문제가 최적화, 경우의 수, 가능 여부 중 무엇을 요구하는지 확인하고 DP 적용 성질을 검토함
2. **상태와 점화식 설계** - 부분 문제를 상태로 정의하고 상태 간 전이 관계와 초기값을 작성함
3. **계산 수행** - top-down 메모이제이션 또는 bottom-up 테이블 방식으로 상태 값을 채움
4. **검증/출력** - 목표 상태의 값과 필요 시 선택 경로를 복원하고 상태 수 기준 복잡도를 산정함

> 요약: DP 절차는 적용 성질을 확인한 뒤 상태와 점화식을 설계하고 표를 채워 최종 상태를 반환하는 흐름임.

- 복잡도는 보통 `상태 수 x 상태당 전이 수`로 설명하면 명확함
- 1차원, rolling array, bitmask 등으로 메모리 압축을 적용할 수 있음
- 최적화 문제에서는 tie-breaking 정책이 실제 해 복원 결과를 바꿀 수 있음

## Ⅴ. 문제점

- **P1 상태 폭발**: 상태 변수와 범위가 많아지면 시간·메모리가 상태 수에 비례해 급격히 증가함
- **P2 점화식 오류**: 상태가 제약을 충분히 담지 못하거나 전이 조건이 빠지면 최적값이 문제의 실제 해와 달라짐
- **P3 계산 순서·초기값 오류**: 기본 상태나 참조 순서가 틀리면 전체 표가 연쇄적으로 잘못 채워짐

> 요약: DP의 핵심 문제는 상태 정의, 전이 관계, 계산 순서 중 하나가 틀릴 때 전체 결과가 무너지는 점임.

## Ⅵ. 개선방안

- **P1 대응**: 상태 압축, 가지치기, sparse table, meet-in-the-middle 등으로 필요한 상태만 계산함 (확인: 상태 수와 메모리 사용량)
- **P2 대응**: 작은 입력의 완전탐색 결과와 DP 결과를 비교하고 점화식의 포괄성과 중복 여부를 검증함 (확인: 교차 검증 테스트)
- **P3 대응**: 초기값 표를 별도로 작성하고 topological order, 반복문 방향, 경계 조건을 단위 테스트함 (확인: 최소 입력과 경계 입력)

> 요약: DP 개선은 상태 공간을 줄이고 작은 사례로 점화식과 계산 순서를 검증하는 방식이 효과적임.

## Ⅶ. 전망

- **향후 발전 방향**: 최적화, 확률 모델, 강화학습, 시퀀스 분석에서 DP 원리는 계속 사용되며, 대규모 문제에서는 근사·압축·병렬화와 결합됨
- **기술사적 판단**: DP 답안은 예제 코드보다 상태 정의와 점화식이 왜 충분한지 설명하는 것이 더 중요함
- **기술사 제언**: 문제를 보면 먼저 탐욕이 가능한지 확인하고, 불가능하면 DP의 상태와 전이로 요구사항을 구조화해야 함

> 요약: DP는 복잡한 최적화 문제를 상태와 점화식으로 바꾸는 핵심 설계 도구이며 검증 가능한 상태 정의가 관건임.
