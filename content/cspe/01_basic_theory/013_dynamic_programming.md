## Ⅰ. 개요

- **정의**: 동적 프로그래밍(DP)은 겹치는 부분 문제의 해를 저장해 재계산을 제거하는 최적화 기법임.
- **배경/필요성**: 순수 재귀는 최적 부분 구조가 성립해도 같은 부분 문제를 호출할 때마다 다시 계산해 지수적 시간이 되므로, 이미 계산한 부분 문제의 결과를 저장해 재사용하는 장치가 필요함. 시험 중 같은 공식을 매번 유도하지 않고 메모지에 적어 참조하는 것과 같은 이치임.
- **출제 의도**: 최적 부분 구조·중복 부분 문제라는 DP 성립 두 조건의 판별력, 점화식 도출 및 Top-down/Bottom-up 구현 선택력, 분할 정복·탐욕과의 구분 판단력을 확인함.
- **답안 방향**: 구조(상태·점화식·메모이제이션/테뷸레이션) → 동작(점화식으로 테이블 채우기) → 비교(분할 정복·탐욕 대비 적용 조건) → 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 적용 조건(성립 여부) 판별 능력 확인 | 최적 부분 구조·중복 부분 문제 두 조건, 상태·점화식 정의 | 두 조건 중 하나만 확인하고 DP로 단정 |
| Top-down/Bottom-up 구현 및 분할 정복·탐욕과의 구분 능력 확인 | 메모이제이션과 테뷸레이션의 차이, 부분 문제 독립성(분할 정복) 대 중복성(DP) | 분할 정복과 DP를 같은 기법으로 혼동 |

> 요약: DP 답안은 최적 부분 구조와 중복 부분 문제라는 두 성립 조건을 먼저 확정하고, 그 위에서 점화식과 구현 방식을 판단해야 함.

## Ⅱ. 구조 및 구성요소

```text
문제(전체) -> 상태 정의(부분 문제 식별) -> 점화식 도출(상태 간 관계)
                                              |
                                              +-> Top-down: 재귀 호출 + 캐시 조회(메모이제이션)
                                              +-> Bottom-up: 반복문 + 배열 채움(테뷸레이션)
                                              |
                                              +-> 기저 조건에서 출발해 상태를 채움 -> 목표 상태 값 = 정답
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 상태(State) | 부분 문제를 고유하게 식별하는 인덱스 | `dp[i]`, `dp[i][j]` |
| 점화식(Recurrence) | 현재 상태를 더 작은 상태들로 표현하는 관계식 | `dp[i] = dp[i-1] + dp[i-2]` |
| 기저 조건(Base Case) | 더 이상 분해되지 않는 최소 상태의 값 | `dp[0]=0`, `dp[1]=1` |
| 메모이제이션(Memoization) | 재귀 호출 결과를 캐시에 저장해 재계산을 차단 | 필요할 때 공식을 유도해 메모(Top-down) |
| 테뷸레이션(Tabulation) | 작은 상태부터 배열을 순서대로 채움 | 시험 전 공식집을 미리 완성(Bottom-up) |

> 요약: 상태와 점화식이 문제를 정의하고, 메모이제이션·테뷸레이션 중 하나의 방식으로 상태값을 채워 목표 상태의 값을 구함.

## Ⅲ. 동작원리 및 흐름도

```text
피보나치 F(5) 계산 예시

[중복 부분 문제 확인] F(5)=F(4)+F(3), F(4)=F(3)+F(2) -> F(3)이 두 갈래에서 각각 필요
  순수 재귀는 F(3)을 매번 처음부터 다시 계산함

[Bottom-up 테뷸레이션으로 상태 채우기]
dp[0]=0 -> dp[1]=1 -> dp[2]=dp[1]+dp[0]=1 -> dp[3]=dp[2]+dp[1]=2
  -> dp[4]=dp[3]+dp[2]=3 -> dp[5]=dp[4]+dp[3]=5
총 계산 5회 (같은 F(5)를 구하는 순수 재귀는 F(3) 중복 포함 15회 호출)
```

- 1단계(상태 정의): 부분 문제를 `dp[i]` 형태로 정의하고 무엇을 인덱스로 삼을지 결정함.
- 2단계(점화식 도출): `dp[i]`를 더 작은 상태(`dp[i-1]`, `dp[i-2]` 등)로 표현하는 관계식을 세움.
- 3단계(테이블 채우기): 기저 조건(`dp[0]`, `dp[1]`)부터 출발해 Top-down(재귀 호출 시 캐시를 먼저 조회하고 없으면 계산 후 저장) 또는 Bottom-up(반복문으로 작은 인덱스부터 순서대로 계산) 중 하나로 `dp` 배열을 채움.
- 4단계(정답 추출): 목표 상태(`dp[N]`)의 값을 최종 답으로 반환함. 이 과정에서 각 상태는 정확히 한 번만 계산되어 중복이 제거됨.

> 요약: 상태 정의와 점화식 도출 이후 Top-down 또는 Bottom-up 중 하나로 `dp` 테이블을 채우면 각 상태가 한 번만 계산되어 중복 부분 문제가 제거됨.

## Ⅳ. 특징

- 시간복잡도 개선 폭: 시간복잡도는 상태 수와 상태당 전이 비용의 곱으로 결정되며, 피보나치는 순수 재귀 $O(2^N)$에서 DP 적용 시 $O(N)$으로 줄어듦(N=50 기준 약 $10^{15}$회에서 50회로 감소).
- Top-down·Bottom-up 트레이드오프: Top-down은 점화식을 그대로 재귀로 옮겨 구현이 직관적이나 재귀 깊이가 커지면 스택 오버플로우 위험이 있고, Bottom-up은 반복문이라 안전하지만 상태 공간 전체를 채우므로 실제로 필요한 상태가 희소한 문제에서는 불필요한 계산이 늘어남.
- 공간 최적화 여지: 점화식이 직전 몇 개 상태만 참조하면(예: `dp[i] = dp[i-1] + dp[i-2]`) 전체 배열 대신 변수 몇 개만 유지하는 슬라이딩 윈도우로 $O(N)$ 공간을 $O(1)$로 줄일 수 있음.
- 상태 설계의 난이도: DP의 성패는 상태를 몇 차원으로, 무엇을 인덱스로 정의하느냐에 달려 있으며, 상태 차원이 부족하면 제약 조건 누락으로 오답이, 과도하면 시간·공간 낭비가 발생함.

> 요약: DP의 이득은 상태 수만큼의 계산으로 중복을 제거하는 데서 나오며, 그 이득의 크기는 상태 설계와 구현 방식(Top-down/Bottom-up) 선택에 좌우됨.

## Ⅴ. 심화 비교 및 적용 판단

| 판단 기준 | 동적 프로그래밍 | 분할 정복 | 탐욕 알고리즘 | 선택 기준 |
|:---|:---|:---|:---|:---|
| 부분 문제 관계 | 중복(겹침) — 저장 필수 | 독립 — 저장 불필요 | 매 단계 한 후보만 선택하고 되돌리지 않음 | 같은 부분 문제가 반복 호출되면 DP를 기본으로 검토 |
| 검토 범위 | 성립 가능한 선택을 모두 검토해 상태값으로 저장 | 재귀적으로 모든 부분 해를 결합 | 현재 최선 후보 1개만 확정 | 국소 최적이 전역 최적임을 증명할 수 있으면 탐욕 |
| 최적해 보장 조건 | 최적 부분 구조만 성립하면 항상 보장 | 최적 부분 구조 성립 시 보장 | 탐욕적 선택 속성까지 추가로 성립해야 보장 | 탐욕적 선택 속성 증명에 실패하면 DP로 전환 |
| 대표 사례 | 0/1 배낭, LCS, 편집 거리 | 병합 정렬, 이진 탐색 | 활동 선택, 허프만 코딩 | — |

> 요약: 부분 문제가 겹치면 DP를 기본으로 검토하되, 탐욕적 선택 속성까지 증명되면 더 경제적인 탐욕법으로, 부분 문제가 독립적이면 분할 정복으로 대체함.

**리스크·대응 (불릿):**
- 상태 정의 오류: 상태 차원을 부족하게 잡으면(예: 무게 제약 차원 누락) 제약 조건을 반영하지 못해 오답이 발생함 → 문제의 모든 제약을 상태 차원에 반영했는지 설계 리뷰 항목으로 고정함(지표: 소규모 입력에서 완전 탐색 결과와의 일치 여부).
- DP 오적용: 부분 문제가 실제로는 독립적인데 DP를 적용해 불필요한 메모리를 사용함 → 부분 문제 중복 여부를 사전에 확인해 중복이 없으면 분할 정복으로 대체함(지표: 캐시 히트율 — 낮으면 중복이 거의 없다는 신호).

**도입 후 점검 지표 (불릿):**
- 정확성: 소규모 입력에서 완전 탐색(Brute Force) 결과와 DP 결과가 일치하는지 검증함.
- 자원: 상태 공간 크기(상태 수 x 전이 비용)가 시간·메모리 제약 내에 있는지 사전 추정함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 문제에 최적 부분 구조와 중복 부분 문제 두 조건이 성립하는지 소규모 사례로 먼저 검증함.
2. 중기: 상태 차원과 점화식을 표준 패턴으로 문서화하고, Top-down/Bottom-up 선택 기준(재귀 깊이, 상태 희소성)을 팀 가이드에 반영함.
3. 장기: 상태 공간이 커지면 공간 최적화(슬라이딩 윈도우)와 근사 기법 병행 적용 기준을 운영 정책에 반영함.

- 기술사적 판단: 부분 문제가 겹치고 최적 부분 구조가 성립할 때만 DP를 선택하며, 탐욕적 선택 속성이 추가로 성립하면 더 경제적인 탐욕법을 우선 검토함.
- 기술사 제언: 상태 정의 오류가 DP 구현 실패의 가장 흔한 원인이므로, 상태 설계를 코드 작성 전 별도 검토 단계로 명시해야 함.
