## 미리 알고가기

- 최적 부분 구조: 큰 문제의 최적해가 작은 문제의 최적해들로 자연스럽게 이어지는 성질임
- 중복 부분 문제: 같은 부분 문제가 여러 경로에서 반복해서 나타나는 특성임
- 메모이제이션: 이미 계산한 결과를 저장해 같은 입력이 들어오면 다시 계산하지 않는 방식임
- 상태 전이: 한 상태의 답을 이전 상태들의 답으로 계산하는 규칙임

## Ⅰ. 개요

- **정의/개념**: 동적 프로그래밍은 큰 문제를 여러 상태로 나눈 뒤, 각 상태의 답을 한 번만 계산해 저장하고 재사용함으로써 전체 계산량을 줄이는 설계 기법임. 전이 규칙과 초기값이 맞게 정의되면 부분 문제의 답을 쌓아 전체 최적해를 구할 수 있음
- **배경/필요성**: 단순 재귀나 완전 탐색은 같은 부분 문제를 여러 번 다시 풀기 때문에 입력이 조금만 커져도 계산량이 급격히 늘어나며, 이를 줄이려면 상태를 정의하고 이미 구한 답을 기억하는 절차가 필요함

## Ⅱ. 특징

- 문제를 상태와 상태 전이로 바꿔 표현하므로, 어디서 계산이 반복되는지와 어떤 정보가 필요한지가 분명해짐
- 한 번 계산한 상태 값을 저장해 같은 부분 문제를 다시 풀지 않으므로 지수 시간 문제를 다항 시간으로 줄이는 경우가 많음
- 재귀 호출과 캐시를 결합한 메모이제이션 방식과, 반복문으로 테이블을 채우는 방식 중 입력 특성에 맞는 구현을 선택할 수 있음
- 상태를 너무 넓게 잡으면 저장 비용이 폭증하고, 너무 좁게 잡으면 정답 조건이 빠지므로 상태 설계가 성능과 정답성을 함께 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 동적 프로그래밍 | 분할 정복 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 같은 부분 문제가 여러 번 반복되어 저장 이점이 큼 | 하위 문제가 서로 독립적이어서 저장 없이도 분해가 가능함 | 각 단계에서 하나의 선택을 바로 확정하는 구조임 |
| 결과 저장 방식 | 상태 값을 테이블이나 캐시에 저장해 다시 사용함 | 보통 저장 없이 하위 문제를 풀고 결과만 결합함 | 이전 선택을 별도로 저장하지 않고 즉시 진행하는 경우가 많음 |
| 정답 보장 조건 | 상태와 전이식이 맞으면 최적해를 보장함 | 문제 구조가 분할과 결합에 맞으면 정답을 구함 | 탐욕적 선택 속성이 성립할 때만 최적해를 보장함 |
| 대표 장점 | 반복 계산을 줄여 큰 입력도 다룰 수 있게 함 | 구조가 단순하고 병렬화하기 쉬움 | 구현이 단순하고 의사결정 속도가 빠름 |

> 요약: 동적 프로그래밍은 부분 문제가 반복된다는 점이 핵심이며, 저장이 필요 없거나 즉시 선택이 가능한 문제와는 접근 자체가 다름

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 | 위치, 길이, 용량, 남은 선택 수처럼 문제를 구별하는 최소 정보 집합임. 정보가 빠지면 오답이 생기고, 정보가 지나치면 상태 수가 불필요하게 늘어남 |
| 전이식 | 현재 상태의 값을 어떤 이전 상태들로부터 계산할지 정한 규칙임. 전이식이 틀리면 저장된 값이 많아도 끝까지 잘못된 답이 누적됨 |
| 초기값 | 더 이상 쪼갤 수 없는 가장 작은 문제의 정답임. 경계 조건을 잘못 두면 이후 모든 상태가 같은 방향으로 틀어짐 |
| 저장 테이블 | 계산한 상태 값을 배열, 맵, 비트마스크 같은 구조에 보관함. 접근 방식과 크기가 시간복잡도와 메모리 사용량을 직접 좌우함 |

```text
+---------+     +-----------+     +-----------+     +-----------+
| 초기값    | --> | 상태 정의    | --> | 전이식      | --> | 저장소 갱신  |
+---------+     +-----------+     +-----------+     +-----------+
```

> 요약: 동적 프로그래밍은 상태, 전이식, 초기값, 저장소가 서로 맞물려야 계산을 줄이면서도 정답을 유지할 수 있음

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상태정의 | --> | 초기값설정 | --> | 전이계산 | --> | 답추출 |
+----------+     +----------+     +----------+     +----------+
```

1. **상태정의**: 문제를 구별하는 최소 정보 집합을 정해 어떤 상태를 저장할지 결정함
2. **초기값설정**: 가장 작은 입력이나 빈 상태처럼 바로 답을 알 수 있는 경계 조건을 먼저 채움
3. **전이계산**: 작은 상태에서 큰 상태로, 또는 필요한 상태가 호출될 때마다 전이식에 따라 값을 계산해 저장함
4. **답추출**: 목표 상태의 값을 읽거나 여러 상태 중 최댓값과 최솟값을 집계해 최종 답을 얻음

## Ⅵ. 실무 적용 및 유의점

1. 편집 거리처럼 같은 부분 문제가 반복되는 계산은 동적 프로그래밍으로 바꾸고 총 계산 시간과 테이블 크기로 확인함
2. 상태를 너무 넓게 잡으면 메모리가 급격히 커지므로 정답에 꼭 필요한 정보만 남기고 상태 수와 피크 메모리로 확인함

## Ⅶ. 결론

동적 프로그래밍은 공식을 많이 아는 기법이 아니라, 반복되는 부분 문제를 어떤 상태와 전이로 압축해 저장할지 설계하는 기법임.
