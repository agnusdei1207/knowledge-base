# 행렬 연산 - 행렬 곱·역행렬·전치 (Matrix Operations)

## 1. 개요

- **정의/개념**: 행렬 연산은 수와 벡터를 직사각형 배열로 표현하고 곱, 역행렬, 전치 등을 통해 선형 관계를 계산하는 방법이다.
- **배경/필요성**: 그래픽스, 통계, 최적화, 머신러닝은 대량의 선형 계산을 행렬 형태로 표현하므로 차원 조건과 연산 비용을 정확히 이해해야 한다.

행렬 연산의 핵심은 값 계산보다 먼저 차원이 맞는지 확인하는 것이다.

## 2. 특징 및 비교

| 연산 | 의미 | 조건 | 주요 활용 |
|---|---|---|---|
| 행렬 곱 | 선형 변환 합성, 가중합 | `A(m x n) * B(n x p)` | 신경망, 그래픽스 |
| 전치 | 행과 열 교환 | 모든 행렬 가능 | 내적, 공분산 |
| 역행렬 | 변환의 역방향 계산 | 정방·가역 행렬 | 선형 방정식 |
| 행렬 분해 | 계산을 안정적 구조로 분해 | 목적별 조건 | 회귀, PCA |

선택 기준은 차원 조건, 계산 복잡도, 수치 안정성, 희소성, 병렬화 가능성이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Row/Column | 행렬의 차원 | 연산 가능 조건 |
| Element | 각 위치의 값 | 데이터 단위 |
| Multiplication Rule | 행과 열의 내적 | `O(n^3)` 기본 비용 |
| Transpose | 축 교환 | 형태 변환 |
| Invertibility | 역행렬 존재 여부 | rank, determinant |

```text
----------+      +----------+      +----------+
| 차원확인 | ---> | 연산수행 | ---> | 결과검증 |
+----------+      +----------+      +----------+
```

차원 확인이 선행되어야 계산 결과의 의미와 비용을 설명할 수 있고, 수치 안정성 문제도 같은 흐름에서 판단된다.

## 4. 문제점 및 개선방안

1. **차원 불일치**
   - 행렬 곱의 내부 차원이 맞지 않으면 연산 자체가 정의되지 않는다.
   - **개선방안**: 연산 전 shape 검증과 단위 테스트를 수행한다.

2. **역행렬 남용**
   - 직접 역행렬 계산은 비용이 크고 수치적으로 불안정할 수 있다.
   - **개선방안**: LU, QR, SVD 분해나 선형 시스템 풀이로 대체한다.

3. **계산 비용 폭증**
   - 큰 밀집 행렬 곱은 시간·메모리 비용이 급격히 커진다.
   - **개선방안**: 희소 행렬, 블록 연산, GPU 병렬화를 활용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 머신러닝 | 행렬 곱으로 배치 추론과 학습 계산 수행 | 처리량, GPU 사용률 |
| 그래픽스 | 좌표 변환을 행렬 합성으로 표현 | 프레임 시간, 변환 정확도 |
| 통계 분석 | 공분산, 회귀, PCA 계산에 행렬 연산 사용 | 조건수, 오차 |

## 6. 결론

행렬 연산은 선형 계산을 구조적으로 표현하는 핵심 도구이다. 행렬 곱·역행렬·전치의 의미를 차원 조건, 계산 복잡도, 수치 안정성까지 연결해야 실제 시스템과 분석 업무에서 올바르게 사용할 수 있다.
