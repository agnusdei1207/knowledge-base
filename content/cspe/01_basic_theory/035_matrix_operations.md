## Ⅰ. 개요

- **정의**: 행렬 연산은 2차원 수 배열인 행렬 간 덧셈·곱셈·전치·역행렬을 정의하는 선형대수의 기본 규칙임.
- **배경/필요성**: 연립방정식·좌표변환·통계 계산을 각 원소마다 스칼라 연산으로 처리하면 식이 커질수록 계산량이 급증하므로, 다수의 곱셈·덧셈을 행렬 곱 하나로 묶어 처리하는 규칙이 필요함.
- **출제 의도**: 행렬 곱의 정의역 조건(열수=행수)과 비가환성(`AB != BA`) 이해, 역행렬 존재 조건(`det(A) != 0`)과 전치의 성질(`(AB)^T = B^T A^T`) 정확성, 곱셈 복잡도 `O(N^3)`와 개선 알고리즘(Strassen) 인지 여부를 확인함.
- **답안 방향**: 구조(연산 종류·차원 조건) -> 동작(곱셈 절차·복잡도 개선) -> 특징(비가환성·존재 조건) -> 비교(곱셈 알고리즘 선택 기준) -> 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 행렬 곱 정의와 연산 규칙 설명 요구 | 차원 조건(`A`가 `m x p`, `B`가 `p x n`), `C_ij = sum_k A_ik B_kj`, `O(N^3)` 복잡도 근거 | 곱셈 순서 교환 가능 단정, 차원 조건 누락, 역행렬 항상 존재한다는 서술 |

> 요약: 행렬 연산 답안은 차원 조건과 비가환성을 먼저 못 박고, 그 위에서 복잡도 개선과 역행렬 존재 조건을 논증해야 함.

## Ⅱ. 구조 및 구성요소

```text
입력 A(m x p), B(p x n) -> 차원 검증(A의 열수 == B의 행수) -> 연산 종류 분기
                                                              |
                                     +-> 덧셈/뺄셈(동일 차원 필요, 원소별 연산)
                                     +-> 곱셈(C_ij = A행 · B열 내적)
                                     +-> 전치(행<->열 인덱스 교환)
                                     +-> 역행렬(det(A) != 0인 정사각 행렬만 존재)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 차원 검증 | 곱셈 시 `A`의 열수와 `B`의 행수 일치 여부 확인 | 톱니바퀴 이가 맞물리는지 확인 |
| 곱셈(내적) | `A`의 행 벡터와 `B`의 열 벡터를 내적해 `C_ij` 산출 | 학생별 과목 점수를 항목별로 합산 |
| 전치(`A^T`) | 행과 열 인덱스를 교환, `(A^T)_ij = A_ji` | 표의 행과 열을 뒤바꿈 |
| 행렬식(`det(A)`) | 정사각 행렬을 스칼라 값으로 환원, 역행렬 존재 여부 판정 | 부피/넓이의 축소·확대 비율 |
| 역행렬(`A^-1`) | `A * A^-1 = I`(단위 행렬)를 만족하는 행렬, `det(A) != 0`일 때만 존재 | 원상태로 되돌리는 연산 |

> 요약: 차원 검증이 곱셈 가능 여부를, 내적·전치가 각 연산의 계산 방식을, 행렬식이 역행렬 존재 여부를 결정함.

## Ⅲ. 동작원리 및 흐름도

```text
차원 확인 -> 원소별 내적 계산(i,j 순회) -> 결과 행렬 채움 -> (필요 시) 역행렬 검증
```

- 1단계(차원 확인): `A(m x p)`, `B(p x n)`에서 `A`의 열수 `p`와 `B`의 행수가 같은지 확인함. 다르면 곱셈이 정의되지 않음.
- 2단계(내적 계산): 각 `(i, j)`에 대해 `C_ij = sum(k=1..p) A_ik * B_kj`를 계산함. 예를 들어 `A = [[1,2],[3,4]]`, `B = [[5,6],[7,8]]`이면 `C_11 = 1*5 + 2*7 = 19`, `C_12 = 1*6 + 2*8 = 22`, `C_21 = 3*5 + 4*7 = 43`, `C_22 = 3*6 + 4*8 = 50`으로 `C = [[19,22],[43,50]]`이 산출됨.
- 3단계(결과 채움): `m x n` 크기의 결과 행렬을 반복 계산으로 채우며, 단순 구현은 3중 반복문으로 `m * n * p`회의 곱셈-덧셈이 필요함.
- 4단계(역행렬 검증): 역행렬이 필요한 경우 `det(A)`를 먼저 계산해 0이 아님을 확인한 뒤 가우스-조르당 소거법 또는 LU 분해로 `A^-1`을 구함. `det(A) = 0`이면 특이 행렬(Singular Matrix)로 역행렬이 존재하지 않음.

$$
T(N) = 7T(N/2) + O(N^2) \;\Rightarrow\; T(N) = O(N^{\log_2 7}) \approx O(N^{2.807})
$$

- 위 점화식은 Strassen 알고리즘의 복잡도임. `2x2` 블록 분할에서 곱셈 8회가 필요한 단순 곱셈과 달리, 7개의 중간값을 재사용해 곱셈을 7회로 줄이고 그 대가로 덧셈을 18회로 늘려 재귀적으로 `O(N^3)`을 `O(N^{2.807})`로 낮춤.

> 요약: 곱셈은 차원 확인 후 내적을 반복해 결과를 채우는 `O(N^3)` 연산이며, Strassen은 곱셈 횟수를 줄이는 방식으로 이를 `O(N^{2.807})`까지 개선함.

## Ⅳ. 특징

- 곱셈 비가환성: `AB`와 `BA`는 일반적으로 결과가 다름. 예를 들어 `A = [[1,1],[0,1]]`, `B = [[1,0],[1,1]]`이면 `AB = [[2,1],[1,1]]`, `BA = [[1,1],[1,2]]`로 서로 다름. 곱셈 순서를 바꿔 계산하면 오답임.
- 결합·분배법칙 성립: `(AB)C = A(BC)`, `A(B+C) = AB+AC`는 성립하므로 곱셈 순서 자체는 유지한 채 묶는 순서만 바꾸는 것은 가능함.
- 전치의 순서 반전: `(AB)^T = B^T * A^T`로, 두 행렬의 곱을 전치하면 각 행렬을 전치한 뒤 곱하는 순서가 뒤바뀜.
- 역행렬 존재 조건: 정사각 행렬이면서 `det(A) != 0`(비특이 행렬)일 때만 역행렬이 유일하게 존재함. 정사각이 아니거나 `det(A) = 0`이면 역행렬 대신 유사역행렬(Moore-Penrose Pseudo-inverse)을 사용함.

> 요약: 행렬 곱은 순서를 바꾸면 결과가 달라지는 비가환 연산이며, 역행렬은 `det(A) != 0`이라는 조건이 충족될 때만 존재함.

## Ⅴ. 심화 비교 및 적용 판단

| 곱셈 알고리즘 | Naive 3중 반복 | Strassen | 선택 기준 |
|:---|:---|:---|:---|
| 시간 복잡도 | `O(N^3)` | `O(N^{2.807})` | `N`이 커질수록 Strassen 이득이 커짐 |
| 구현 복잡도 | 낮음, 캐시 지역성 활용 용이 | 높음, 재귀 분할·중간값 관리 필요 | 라이브러리(BLAS) 활용 시 Naive 기반 최적화가 실무 표준 |
| 수치 안정성 | 상대적으로 안정 | 덧셈 횟수 증가로 부동소수점 오차 누적 가능 | 정밀도가 중요한 계산은 Naive 또는 블록 최적화 선택 |

> 요약: `N`이 크고 정밀도 요구가 낮을 때만 Strassen이 유리하며, 실무 라이브러리는 대개 캐시 최적화된 Naive 기반 블록 곱셈을 기본으로 씀.

**리스크·대응:**
- 역행렬 직접 계산의 수치 불안정: 조건수(Condition Number)가 큰 행렬에서 부동소수점 오차가 증폭되는 것이 원인 → 연립방정식은 `x = A^-1 b` 대신 LU 분해·QR 분해로 풀어 대응함.
- 차원 불일치 오류: 행렬 곱 구현 시 `A`의 열수와 `B`의 행수 검증 누락이 원인 → 연산 전 차원 검증 로직을 표준 함수로 고정해 대응함.

**도입 후 점검 지표:**
- 정확성: 알려진 결과값(단위 행렬 곱, 소규모 손계산 예시)과의 일치 여부로 검증함.
- 수치 안정성: 조건수와 계산 후 잔차(residual) `||Ax - b||`가 허용 오차 이내인지 실측으로 확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 행렬 연산이 들어가는 모듈에서 차원 검증과 `det(A) != 0` 확인 로직을 코드 리뷰 체크리스트에 반영함.
2. 중기: 대규모 행렬 곱은 BLAS(cuBLAS 등) 기반 라이브러리로 대체해 캐시 최적화·GPU 가속 이득을 확보함.
3. 장기: 조건수가 큰 계산이 반복되는 시스템은 LU/QR 분해 기반 파이프라인으로 전환해 수치 안정성을 표준화함.

- 기술사적 판단: 곱셈 순서·차원 조건·역행렬 존재 조건은 구현 전 항상 명시적으로 검증해야 하며, 알고리즘 선택은 정밀도 요구와 `N` 크기를 함께 고려해 결정함.
- 기술사 제언: 연립방정식을 역행렬 직접 계산으로 푸는 관행을 지양하고, LU/QR 분해 기반 표준 루틴을 팀 공용 라이브러리로 강제함.
