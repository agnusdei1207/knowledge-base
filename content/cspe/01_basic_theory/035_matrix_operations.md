# 📖 【암기용】 개념 완전 이해

> 목적: 행렬 연산을 컴퓨터 과학 관점에서 완벽히 이해하게 만든다. 단순 수학이 아니라 컴퓨터가 왜 행렬을 쓰는지 직관을 제공한다.

## 한눈에
- **개요**: 행렬(Matrix)은 숫자들을 직사각형 형태로 배열한 것이며, 행렬 연산(곱셈, 역행렬, 전치)은 수많은 데이터와 수식을 한 번에 병렬로 처리하기 위한 수학적 도구다.
- **왜 필요한가**: 3D 그래픽스에서 물체를 회전시키거나, 딥러닝에서 수만 개의 가중치를 계산할 때, 개별 수식으로 풀면 코드가 무한히 길어진다. 행렬 연산은 이를 단일 수식으로 압축하고 GPU의 병렬 처리를 가능하게 한다.
- **핵심 직관**: 엑셀 표(데이터)에 마법의 필터(변환 행렬)를 씌워 전체 데이터를 한 방에 조작하는 과정이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 행렬 곱 (Matrix Multiplication, $AB$) | 두 행렬의 행과 열을 내적하여 결합하는 연산 | 여러 단계의 공정(함수 합성)을 한 번의 공정으로 합치는 것 |
| 전치 행렬 (Transpose, $A^T$) | 행렬의 행과 열을 맞바꾼 행렬 (대각선 대칭) | 엑셀에서 표의 가로/세로 방향을 전환하는 것 |
| 역행렬 (Inverse, $A^{-1}$) | 어떤 행렬과 곱했을 때 항등행렬($I$)이 되는 행렬 | 암호화된 데이터를 원래 평문으로 되돌리는 '해독키' |

## 깊이 이해
- **배경·문제의식**: 연립방정식 미지수가 100개라면 식도 100개 필요하다. 이를 일일이 코딩할 수 없다. 수학자들은 계수들만 뽑아 표로 묶은 뒤 $Ax = b$ 라는 하나의 식으로 추상화했다. 이것이 선형대수학의 시작이다.
- **작동 원리**: 행렬 곱은 "공간의 변환"을 연속으로 적용하는 것이다. 전치 행렬은 데이터의 차원 방향을 바꿔 연산을 용이하게 하며, 역행렬은 $Ax=b$에서 $x = A^{-1}b$로 미지수를 단숨에 구하는 마스터키 역할을 한다.
- **비유**: 3D 게임에서 캐릭터가 '이동'하고 '회전'하는 것은 두 가지 변환이다. 이동 행렬 $M$과 회전 행렬 $R$을 먼저 곱해 합성 행렬 $C = R \times M$을 만들면, 캐릭터의 1만 개 꼭짓점에 $C$를 한 번만 곱해 위치를 즉시 계산할 수 있다.
- **구체 예시**: 딥러닝에서 입력 벡터 $x$(100차원)와 가중치 행렬 $W$(100x50)를 곱하면 단 한 줄의 코드 `y = np.dot(x, W)`로 5,000번의 곱셈과 덧셈을 수행하여 50차원 출력 $y$를 얻는다.
- **흔한 오해·주의점**: 행렬 곱은 교환법칙이 성립하지 않는다 ($AB \neq BA$). 양말을 신고 신발을 신는 것과 신발을 신고 양말을 신는 결과가 다르듯, 변환의 순서가 중요하기 때문이다.

## 연결 개념
- 선형 변환 — 행렬을 곱한다는 것의 기하학적 의미 (공간을 늘리거나 회전시킴)
- GPU (Graphics Processing Unit) — 행렬 연산(특히 곱셈)을 병렬로 수천 개씩 동시 처리하는 하드웨어
- 고유값 분해 (Eigendecomposition) — 복잡한 행렬 거듭제곱을 쉽게 하기 위해 행렬의 뼈대만 추려내는 기법

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 행렬 연산은 다차원 데이터와 다원 1차 연립방정식을 텐서(Tensor) 형태로 추상화하여, 선형 변환과 시스템 모델링을 단일 수식으로 처리하는 수학적 기법이다.
> 2. **가치**: 데이터의 대량 병렬 처리(SIMD)를 가능하게 하여, 3D 그래픽스의 기하 변환과 인공신경망의 가중치 학습(Backpropagation)을 GPU 기반으로 고속 연산할 수 있게 한다.
> 3. **판단 포인트**: 컴퓨터 과학 관점에서는 단순 연산 규칙보다 행렬 곱($O(N^3)$)의 시간 복잡도 문제와 역행렬 계산의 비용 및 대안(LU 분해, SVD)을 서술해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 컴퓨터 연산에서 행렬의 역할 이해 | 딥러닝 연산, 3D 변환 등에서의 병렬 처리 가치 | 단순 수학 공식만 나열하고 응용 분야 누락 |
| 연산 복잡도와 최적화 기법 판단 | 행렬 곱의 $O(N^3)$ 복잡도, 슈트라센 알고리즘 | 역행렬 연산 비용을 무시한 알고리즘 설계 서술 |

> 요약: 행렬 연산이 딥러닝과 그래픽스에서 어떻게 응용되는지 보여주고, 하드웨어적 병렬 처리와 알고리즘적 복잡도 개선 방안을 연결해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 행렬 연산은 데이터 배열에 대한 덧셈, 스칼라 곱, 행렬 곱, 전치 및 역행렬 변환을 통해 다변수 선형 시스템을 일괄 처리하는 수학적 기법임
- 배경: 인공지능, 빅데이터, 컴퓨터 비전 등에서 수백만 개의 변수가 얽힌 연립방정식을 실시간으로 풀어야 하는 요구가 폭증함
- 필요성: 순차적 CPU 연산의 한계를 극복하기 위해, 다중 데이터를 한 번의 명령어(SIMD)로 처리하는 GPU 병렬 컴퓨팅의 이론적 토대 제공이 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
Input Vector (X) -> [ Linear Transformation (Matrix W) ] -> Output Vector (Y)
                            |
                     (GPU 기반 병렬 곱셈 연산)
```

| 연산 종류 | 수학적 표기 및 조건 | 컴퓨터 과학적 의미 |
|:---|:---|:---|
| 행렬 곱 (Multiplication) | $C = AB$ (단, $A$열수 = $B$행수) | 여러 선형 변환의 합성, 딥러닝의 Forward 연산 |
| 전치 행렬 (Transpose) | $A^T$ ($a_{ij} \to a_{ji}$) | 데이터 차원 재배열, 메모리 접근 효율성(Cache) 개선 |
| 역행렬 (Inverse) | $A^{-1}$ ($AA^{-1} = I$) | 변환의 되돌림, 선형 연립방정식의 해($x=A^{-1}b$) 도출 |
| 항등 행렬 (Identity) | $I$ (대각선 원소 1) | 어떠한 변환도 주지 않는 기준 상태 (단위 연산) |

> 요약: 행렬 곱은 공간의 변환 및 합성을, 전치는 데이터 방향 전환을, 역행렬은 변환의 역산을 수행하여 시스템을 제어함.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 행렬화 -> 메모리 연속 할당 -> GPU 스레드 블록 분배 -> MAC(단일 사이클 내적) 연산 -> 결과 병합
```

- 1단계 [행렬 구성]: 다변수 입력 데이터와 가중치(변환식)를 각각 2차원 이상의 행렬 및 텐서 구조로 메모리에 매핑함
- 2단계 [블록 분할 및 스케줄링]: 거대 행렬 곱셈을 연산 효율을 위해 작은 타일(Tile)로 분할하고 GPU의 각 멀티프로세서(SM)에 할당함
- 3단계 [내적(MAC) 병렬 연산]: 행렬 곱 $c_{ij} = \sum a_{ik}b_{kj}$를 단일 명령어 스레드에서 Multiply-Accumulate(MAC) 유닛을 통해 동시 다발적으로 계산함
- 4단계 [역행렬/최적화 적용]: 시스템의 해를 구할 때 비용이 큰 역행렬 계산($O(N^3)$) 대신 가우스-조던 소거법이나 LU 분해로 치환하여 결과를 도출함

> 요약: 행렬 연산은 독립적인 내적 연산의 집합이므로, 이를 GPU의 수천 개 코어에 분산 할당하여 연산 병목을 해소하는 것이 동작의 핵심임.

---

## Ⅳ. 특징

- 교환법칙 불성립: $AB \neq BA$, 즉 변환의 순서가 결과에 결정적 영향을 미치므로 파이프라인 설계 시 순서 보장이 필수임 (단, 결합법칙 $A(BC) = (AB)C$는 성립)
- 병렬 처리 친화성(Embarrassingly Parallel): 각 원소의 연산이 타 원소에 독립적이므로 분산 컴퓨팅 및 병렬 하드웨어(TPU, NPU) 최적화에 극도로 유리함
- 고비용 역산 복잡도: 정사각행렬의 역행렬을 직접 구하는 것은 연산량이 막대하며, 행렬식(Determinant)이 0인 특이 행렬(Singular)일 경우 역행렬 자체가 존재하지 않는 리스크가 있음

> 요약: 행렬 연산은 병렬성에 최적화되어 있으나 비가환성(순서 중요)과 특이 행렬 리스크, 역행렬 연산의 높은 복잡도라는 한계를 가짐.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 표준 행렬 곱 ($O(N^3)$) | 슈트라센 알고리즘 ($O(N^{2.81})$) | 선택 기준 |
|:---|:---|:---|:---|
| 동작 방식 | 3중 for문을 통한 행/열 전수 내적 | 분할 정복을 통해 곱셈 횟수를 8회에서 7회로 축소 | 행렬 크기 $N$의 임계값 초과 여부 |
| 메모리 소모 | 추가 메모리 불필요 ($O(1)$) | 중간 결과 저장을 위한 추가 메모리 필요 | 가용 메모리 대역폭(SRAM) 크기 |
| 실무 적용 | 크기가 작은 행렬, GPU MAC 유닛 | $N$이 수백~수천 이상인 거대 희소/밀집 행렬 | 하드웨어 아키텍처 특성 |

> 요약: 행렬 크기가 작고 하드웨어 MAC 유닛이 지원될 때는 표준 곱셈을, 극거대 행렬의 CPU 연산 시에는 슈트라센(Strassen) 등 알고리즘 최적화를 선택함.

**리스크 및 대응 방안:**
- 특이 행렬(Singular Matrix) 리스크: 변수 간 선형 종속으로 역행렬 계산 불가 → 유사 역행렬(Pseudo-inverse, 무어-펜로즈 역행렬) 적용으로 근사해 도출 (지표: 행렬식 $det(A) == 0$ 여부)
- 행렬 크기 폭증 리스크: 추천 시스템 등에서 빈 공간이 많은 거대 행렬 연산 시 메모리 초과 → 희소 행렬(Sparse Matrix) 압축 포맷(CSR, COO) 사용 및 SVD 차원 축소 적용 (지표: 메모리 Hit-rate)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 딥러닝 가속기(TPU) 설계: 시스톨릭 어레이(Systolic Array) 구조를 하드웨어로 구현하여 데이터 이동을 최소화하고 행렬 내적 연산을 파이프라인 방식으로 실시간 가속
2. 3D 그래픽 엔진 (DirectX/OpenGL): 동차 좌표계(Homogeneous Coordinates) 기반의 $4 \times 4$ 행렬로 이동, 회전, 크기 변환을 단일 행렬로 합성(결합법칙)하여 수백만 폴리곤 정점 변환 연산량 최소화
3. 추천 시스템 차원 축소: 넷플릭스 등에서 수억 명의 유저-아이템 평가 행렬을 특이값 분해(SVD)나 교대 최소제곱법(ALS) 기반의 행렬 분해(Matrix Factorization)로 저차원 근사하여 연산량 절감

**결론 (2줄):**
- 기술사 판단: 현대 컴퓨팅의 성능 병목은 행렬 연산 속도에 종속되므로, 소프트웨어적 알고리즘 개선(분할정복, 희소 압축)과 하드웨어적 병렬화(GPU, NPU)의 동시 설계(Co-design)가 필수적이다.
- 향후 방향: 최근 양자 컴퓨터의 HHL 알고리즘이 선형 연립방정식을 $O(\log N)$에 풀 수 있음을 증명함에 따라, 차세대 양자 기계학습(QML)의 핵심 연산으로 진화하고 있다.
