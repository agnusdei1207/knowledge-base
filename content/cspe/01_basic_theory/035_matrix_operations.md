## 미리 알고가기

- 차원: 행렬의 행과 열 개수임
- 전치 $A^T$: 행과 열을 바꾼 행렬임
- 역행렬 $A^{-1}$: $AA^{-1}=I$를 만족하는 행렬임

## Ⅰ. 개요

- **정의/개념**: 행렬 연산은 다수의 수를 구조적으로 배치한 행렬에 대해 곱셈, 전치, 역행렬, 분해 등을 수행해 선형 관계를 계산하는 기본 수학 연산임
- **배경/필요성**: 그래픽 변환, 신호 처리, 최적화, AI는 모두 벡터와 행렬 형태의 선형 계산을 중심으로 동작하므로 고속 행렬 연산이 필수임

## Ⅱ. 특징

- 행렬 곱은 여러 선형 변환을 하나의 연산으로 합성함
- 전치는 내적, 공분산, 메모리 배치 최적화에 자주 쓰임
- 역행렬은 연립방정식 해석에 중요하지만 수치적으로 불안정할 수 있음
- 대규모 계산에서는 이론식보다 캐시 지역성과 병렬성이 성능을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 행렬 곱 | 전치 | 역행렬 |
|:---|:---|:---|:---|
| 목적 | 선형 변환 합성 | 축 전환 | 선형 시스템 역해석 |
| 차원 제약 | 내적 차원 일치 필요 | 항상 가능 | 정방행렬 + 가역성 필요 |
| 계산 비용 | 큼 | 낮음 | 매우 큼 |
| 대표 적용 | AI, 그래픽 | 데이터 재배치 | 해 찾기, 제어 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 행/열 차원 | 연산 가능 여부를 결정하고 shape mismatch를 막음 |
| 원소 접근 패턴 | 메모리 접근 순서를 정하고 캐시 효율과 직결됨 |
| 분해 기법 | LU, QR, SVD 등이며 직접 역행렬보다 안정적임 |
| 수치 정밀도 | 오차 누적에 영향 줌 float 선택이 중요함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 차원확인 | --> | 연산선택 | --> | 원소계산 | --> | 결과검증 |
+----------+     +----------+     +----------+     +----------+
```

1. **차원확인**: 행과 열 크기가 연산 조건을 만족하는지 봄
2. **연산선택**: 곱, 전치, 분해, 역행렬 중 목적에 맞는 방식을 고름
3. **원소계산**: 정의에 따라 각 원소를 계산하거나 분해함
4. **결과검증**: 오차와 조건 수를 확인해 결과를 검증함

## Ⅵ. 문제점 및 해결 방안

1. **직접 역행렬 계산이 불안정함**: ill-conditioned matrix는 오차가 증폭됨
   - **해결 방안**: 역행렬 대신 LU/QR 분해로 해를 구하고 condition number로 검증함
2. **대규모 곱셈은 메모리 병목이 큼**: 연산량보다 데이터 이동이 느릴 수 있음
   - **해결 방안**: block matrix와 BLAS, GPU를 사용하고 FLOPS utilization로 검증함
3. **shape 오류가 자주 발생함**: 차원 불일치로 계산이 실패함
   - **해결 방안**: 텐서 shape 검증과 타입 힌트를 적용하고 runtime error 수로 검증함

## Ⅶ. 적용 사례

- 딥러닝 학습: 가중치와 입력의 행렬 곱을 반복 수행함, 확인 지표는 throughput과 수렴 안정성임
- 3D 그래픽스: 회전, 이동, 투영을 행렬 곱으로 합성함, 확인 지표는 프레임 지연시간임
- 추천/통계 분석: 공분산과 선형 해를 계산함, 확인 지표는 계산 정확도와 실행시간임

## Ⅷ. 결론

행렬 연산은 수학 정의보다 수치 안정성과 메모리 접근 효율이 실제 성능을 좌우하므로, 문제 크기에 맞는 분해와 실행 구조를 선택해야 함.
