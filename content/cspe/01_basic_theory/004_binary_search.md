# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **정렬된 데이터**를 전제로 탐색 범위를 절반씩 줄이는 **분할 정복** 탐색 — **O(log n)**에 목표값을 찾음
- **왜 필요한가**: 수억 건의 데이터에서 하나씩 처음부터 찾는 선형 탐색은 최악의 경우 수억 번을 조회하지만, 이진 탐색은 단 30번 내외로 값을 확정할 수 있어 압도적으로 빠르다.
- **핵심 직관**: 업다운(Up-Down) 게임과 같다. 1~100 사이 숫자 맞추기를 할 때 "50"을 부르고 크다/작다 피드백에 따라 절반씩 날려버리는 원리.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유·예 |
|:---|:---|:---|
| 정렬 전제 | 데이터가 정렬돼 있어야만 성립하는 선행조건 | 사전이 가나다순이어야 절반씩 찾음 |
| 분할 정복 | 문제를 절반씩 나눠 푸는 전략 | 매번 범위를 반으로 접음 |
| Left / Right | 현재 탐색 중인 구간의 양 끝 인덱스 | 책을 펼쳐 놓은 왼쪽·오른쪽 경계 |
| Mid | 구간의 중앙, Target과 비교하는 기준 | 지금 펼친 페이지 |
| Target | 찾으려는 값 | 찾는 이름 |
| O(log n) | 매번 절반으로 줄어드는 탐색 속도 | 100만 건도 약 20번이면 확정 |

## 깊이 이해

### 왜 이렇게까지 빠른가 (log n의 의미)
- 매 비교마다 후보를 절반씩 버리므로, n개에서 답을 확정하는 데 필요한 횟수는 "n을 몇 번 반으로 나눠야 1이 되나" = log₂n이다.
- 100만 건이면 2²⁰≈100만이라 약 20번, 10억 건이어도 약 30번이면 끝난다. 선형 탐색(최대 n번)과는 비교 불가한 격차다.

### 실제 동작 (예: 정렬된 배열에서 7 찾기)
- [1, 3, 5, 7, 9, 11]에서 7 탐색: 중앙값 5와 비교 → 7>5라 오른쪽 절반으로. 다음 중앙값 9와 비교 → 7<9라 왼쪽으로. 다음 중앙값 7 → 일치, 종료.
- 매 단계 Left/Right로 유효 구간을 좁히고, Left가 Right를 넘어 교차하면 "없음"으로 판정한다.

### 구현에서 반드시 조심할 두 가지
- **오버플로우**: `Mid=(Left+Right)/2`는 Left+Right가 정수 최대값을 넘으면 음수가 된다. `Mid=Left+(Right-Left)/2`로 써야 안전하다.
- **경계 조건**: Left≤Right 조건과 Mid±1 갱신을 틀리면 무한 루프나 한 칸 놓침(off-by-one)이 난다. 이진 탐색 버그의 대부분이 여기서 나온다.

### 언제 쓰면 안 되나
- 대전제는 "정렬돼 있고, 인덱스로 임의 접근(O(1))이 된다"이다. 연결 리스트는 중앙 접근이 O(n)이라 이점이 사라진다.
- 삽입·삭제가 잦으면 매번 재정렬(O(n log n)) 비용이 커서, 정렬 상태를 스스로 유지하는 트리(BST·B-Tree)나 해시(005)를 쓴다.

### 확장 개념
- 값이 아니라 조건을 이분하는 파라메트릭 서치, 특정 값 이상이 처음 나오는 위치를 찾는 Lower/Upper Bound가 같은 원리의 변형이다.

### 흔한 오해·주의점
- "정렬만 돼 있으면 무조건 이진 탐색이 유리"는 절반만 맞다. 한 번 찾고 말면 정렬 비용(O(n log n))이 탐색 이득을 넘어설 수 있다 — 같은 데이터를 여러 번 조회할 때 이득이 커진다.

## 연결 개념
- 정렬 알고리즘 (이진 탐색의 선행 조건)
- 이진 탐색 트리 (BST), B-Tree (DB 인덱스)
- 시간복잡도 O(log N)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이미 정렬된 배열 속성을 활용해 매 비교마다 탐색 공간을 1/2로 단축하는 분할 정복(Divide & Conquer) 탐색 기법이다.
> 2. **가치**: 빅데이터 환경에서 선형 탐색의 지연을 O(log n)으로 압축하여 억 단위 레코드 조회를 밀리초(ms) 단위로 보장한다.
> 3. **판단 포인트**: 읽기 성능은 극대화되나 선행 정렬 비용이 크므로, 삽입/삭제가 빈번한 OLTP 환경에서는 배열 대신 B-Tree 등 트리 기반 구조로 전환 적용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대용량 데이터 고속 검색 원리 구조화 | Mid 산출, Left/Right 포인터 이동 로직, O(log N) 보장 원리 | 탐색 로직만 쓰고 정렬 필수라는 전제조건을 누락 |
| 자료구조 선택에 따른 Trade-off 분석 | 배열(이진 탐색) vs 트리(BST) vs 해시(Hash) 장단점 비교 | 삽입/삭제 성능 저하 리스크 언급 누락 |

> 요약: 배열 기반 이진 탐색은 정적인 대규모 읽기 작업에 최적이나, 동적 데이터 환경에서는 삽입 한계 극복을 위한 다른 자료구조와의 비교 선택이 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: 정렬된 데이터 집합에서 중앙값을 임계점으로 설정해 탐색 범위를 절반씩 좁혀나가는 탐색 알고리즘
- 배경: 비정렬 선형 탐색은 데이터가 Tbyte 규모로 확장될 때 CPU 점유 및 응답시간 지연 병목 유발
- 필요성: RDBMS 인덱스 탐색 및 빅데이터 조회 시, 조회 지연을 묶어 서비스 SLA(p99 50ms 등)를 보장하기 위해 필수

---

## Ⅱ. 구조 및 구성요소

```text
정렬된 데이터 
 -> Left, Right 인덱스 초기화 
 -> Mid 산출 
 -> Target 비교 후 Left/Right 이동 
 -> Hit 또는 Fail 반환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정렬된 배열 | 이진 탐색을 수행하기 위한 연속적 메모리 공간 | 데이터 추가/삭제 시 오버헤드 발생 |
| Left / Right 포인터 | 현재 탐색 유효 구간의 양 끝단 인덱스 | 범위가 축소되며 최종 교차 시 탐색 실패 |
| Mid 포인트 | 1/2 분할 기준점이자 Target 값과의 비교 대상 | 오버플로우 방지를 위해 Left + (Right-Left)/2 권장 |

> 요약: 이진 탐색의 구조적 핵심은 인덱스를 통한 랜덤 접근이 지원되는 배열에서만 온전한 O(log N) 효율을 낸다는 것이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
검색 요청(Target) -> 정렬 여부 검증 -> Mid 값 검사 
                      |-> Target == Mid : 반환 후 종료
                      |-> Target < Mid  : Right = Mid - 1
                      +-> Target > Mid  : Left = Mid + 1
```

- 1단계 [구간 설정]: Left ≤ Right인 동안 반복함
- 2단계 [중간값 비교]: Mid = Left + (Right−Left)/2를 구해 Target과 대소를 비교함
- 3단계 [절반 폐기]: 대소 결과에 따라 유효하지 않은 절반 구간을 버림
- 4단계 [종료 처리]: 일치하면 값을 반환하고, Left > Right로 교차하면 없음(Fail)으로 처리함

> 요약: 비교할 때마다 후보군이 N→N/2→N/4로 줄어드는 분할 정복 패턴임.

## Ⅳ. 주요 탐색 알고리즘 심화 비교

| 비교 축 | 이진 탐색 (Binary Search) | 선형 탐색 (Linear Search) | 해시 탐색 (Hash Search) | 이진 탐색 트리 (BST) |
|:---|:---|:---|:---|:---|
| 시간복잡도(평균) | O(log N) | O(N) | O(1) | O(log N) |
| 선행 조건 | 완벽한 정렬 필수 | 제약 없음 (비정렬 가능) | 충돌 제어 함수 | 노드별 크기 규칙 기반 연결 |
| 동적 데이터 대응 | 매우 취약 (삽입 시 재정렬 필요) | 우수 (맨 끝 추가 가능) | 매우 우수 | 우수 (포인터 변경 가능) |
| 메모리 제약 | 배열 등 연속 메모리 요구 | 제약 없음 | 고정 여유 공간 필요 | 비균형 트리 시 최악 O(N) |

> 요약: 정적 캐시 데이터 조회는 이진 탐색이, 동적 추가/수정이 빈번한 인덱스는 B-Tree 계열이, 고속 1:1 매핑은 해시가 유리하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 배열 기반 이진 탐색 | Learned Index (모델 기반 탐색) | 선택 기준 |
|:---|:---|:---|:---|
| 탐색 원리 | Left/Right 포인터로 절반씩 축소 | 학습된 회귀 모델이 데이터 내 대략적 위치를 직접 예측 | 데이터 분포의 예측 가능성 |
| 보장 성능 | O(log N) 항상 보장 | 예측 오차 범위 내 로컬 보정 탐색 필요 | 최악 성능의 수학적 보장 필요 여부 |
| 갱신 비용 | 삽입 시 재정렬 필요 | 분포 변화 시 모델 재학습 필요 | 데이터 갱신 빈도 및 재학습 자원 |

> 요약: 정적이고 예측 가능한 분포에서는 Learned Index가 이진 탐색보다 빠를 수 있으나, 보장된 최악 성능이 필요하면 전통적 이진 탐색을 채택한다.

**주요 리스크·대응:**
- 인덱스 계산 오버플로우: (Left+Right)가 정수 최대값을 초과 → Mid = Left + (Right−Left)/2로 계산 (지표: 배열 인덱스 범위 초과 여부)
- 삽입/삭제 오버헤드: 배열 중간 요소를 바꾸면 뒤 원소를 모두 밀어야 함 → B-Tree 구조로 전환 (지표: 쓰기 연산 시 응답 시간)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Lower/Upper Bound 탐색 확장: 타겟 이상의 값이 최초로 등장하는 위치(Lower Bound)를 찾아 범위 검색에 활용
2. 파라메트릭 서치(Parametric Search) 적용: 최적화 문제를 결정 문제로 바꾼 후 최적의 매개변수를 좁혀나가는 기법에 적용
3. 읽기 중심 빅데이터 캐시 시스템: 변경이 거의 일어나지 않는 일 단위 기준 정보를 메모리 배열에 올려 성능 극대화

**결론 (2줄):**
- 기술사 판단: 이진 탐색은 강력한 조회 성능을 제공하지만, 정렬 유지 비용이 크므로 데이터의 라이프사이클 분석 후 채택해야 한다.
- 향후 방향: 기계학습 모델이 데이터 분포를 학습해 탐색 위치를 직접 추론하는 Learned Index 구조가 차세대 기법으로 부상 중이다.
