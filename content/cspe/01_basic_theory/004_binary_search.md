# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 이진 탐색(Binary Search)은 **정렬된** 배열에서 탐색 구간을 매번 절반으로 버려 목표 값을 찾는 **분할 정복** 기반 탐색 알고리즘으로, 시간 복잡도 **O(log N)**을 달성한다.
- **왜 필요한가**: 앞에서 하나씩 훑는 순차 탐색은 O(N)이라 100만 건에서 최대 100만 번을 비교하지만, 이진 탐색은 약 20번으로 끝나기 때문이다(O(log N)의 성능 의미는 001·002 참조).
- **핵심 직관**: "정렬돼 있다면, 가운데를 찍고 목표와 비교해 못 맞은 절반은 통째로 버린다" — 국어사전에서 중간을 펴 보고 앞·뒤 반을 건너뛰는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

003(정렬)이 만들어 준 '정렬된 상태'를 전제로 삼으므로, 여기서는 탐색 구간을 좁히는 데 쓰는 고유 용어를 세운다. 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 이진 탐색 (상위 키워드) | 정렬 배열을 반씩 좁혀 값을 찾는 탐색 | 사전을 반씩 펼쳐 단어 찾기 |
| 정렬 전제 (Precondition) | 데이터가 오름/내림차순으로 정렬돼 있어야 성립 | 사전이 가나다순이어야 반씩 넘길 수 있음 |
| 탐색 구간 (low·high) | 아직 목표가 있을 수 있는 배열의 시작·끝 인덱스 | "지금 뒤질 범위는 300~350쪽" |
| 중앙값 (mid) | 구간의 가운데 인덱스, `(low+high)/2` | 지금 펼쳐 볼 정확히 가운데 쪽 |
| 분할 정복 (Divide & Conquer) | 문제를 절반으로 쪼개 한쪽만 재귀로 푸는 설계 | 남은 절반만 다시 같은 방식으로 |
| log₂N (탐색 횟수) | N을 1이 될 때까지 2로 나눈 횟수 | 100만→약 20회, 10억→약 30회 |
| 반복형/재귀형 | 루프로 구간을 줄이거나 재귀 호출로 좁히는 두 구현 | 같은 원리, 스택 사용만 다름 |

## 깊이 이해
- **배경·문제의식**: 순차 탐색(O(N))은 데이터가 커질수록 선형으로 느려진다. 그러나 데이터가 이미 **정렬돼 있다면**(003이 보장) "중간값보다 크냐 작냐"만으로 후보의 절반을 한 번에 배제할 수 있다는 통찰이 이진 탐색의 출발점이다.
- **작동 원리 (어떻게+왜)**:
  - 구간 `[low, high]`의 중앙 `mid`를 정하고 `arr[mid]`와 목표를 비교한다.
  - 목표가 더 크면 왼쪽 절반은 볼 필요가 없으므로 `low = mid+1`, 더 작으면 `high = mid-1`로 구간을 반으로 줄인다. 같으면 발견이다.
  - 매 비교마다 후보 수가 N→N/2→N/4로 줄어 1이 되기까지 log₂N번이면 끝난다 — 이것이 O(log N)의 근거다.
- **비유**: 1~1000 숫자 맞히기 게임에서 상대가 "더 위/아래"만 알려줘도, 매번 남은 범위의 가운데를 부르면 10번 안에 맞힌다(2¹⁰=1024). 한 칸씩 부르면 최대 1000번이다.
- **구체 예시**: 정렬된 100만(10⁶) 건에서 순차 탐색은 최악 10⁶회, 이진 탐색은 log₂(10⁶)≈20회다. 약 5만 배 차이다. 10억(10⁹) 건도 약 30회면 끝난다.
- **흔한 오해·주의점**:
  - **정렬 안 된 배열엔 못 쓴다.** 정렬 비용 O(N log N)이 탐색을 압도하므로, 1회성 탐색이면 순차 탐색이 낫고, **정렬을 한 번 해 두고 여러 번 탐색**할 때만 이진 탐색이 이득이다.
  - 중앙값 계산을 `(low+high)/2`로 하면 큰 인덱스에서 오버플로가 날 수 있어, `low + (high-low)/2`가 안전하다.
  - 연결 리스트(006)처럼 임의 접근(random access)이 안 되는 구조에는 mid로 한 번에 못 뛰어 O(log N)이 무너진다 — 배열이라야 성립한다.

## 연결 개념
- **정렬 알고리즘 (003)**: 이진 탐색의 전제 조건인 '정렬된 상태'를 만들어 주는 선행 단계.
- **빅오 표기법 (002)**: O(log N)이 O(N)보다 우월한 이유의 표기적 근거.
- **B-Tree·이진 탐색 트리**: "반씩 좁히기"를 디스크·동적 데이터로 확장한 인덱스 구조.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진 탐색은 정렬된 배열의 탐색 구간을 매 비교마다 절반으로 배제해 O(log N)에 목표를 찾는 분할 정복 알고리즘임.
> 2. **가치**: 100만 건을 약 20회 비교로 탐색해, 대용량 인덱스·검색의 응답성을 결정함.
> 3. **판단 포인트**: 정렬 전제와 임의 접근이 성립할 때만 유효하며, 정렬 비용을 여러 탐색으로 상각할 수 있는지가 채택 기준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 분할 정복 탐색 원리 이해 | 정렬 전제·구간 절반 배제·O(log N) | 정렬 전제 누락, 복잡도 O(N)으로 오기 |
| 순차 탐색 대비 우열 판단 | log₂N vs N의 규모별 격차 | 무조건 이진 탐색 우월로 단정 |
| 적용 조건 한정 능력 | 임의 접근·정렬 상각 조건 명시 | 연결 리스트에도 적용된다는 오류 |

> 요약: 정렬 전제 아래 구간 절반 배제로 O(log N)을 얻는 원리와, 정렬 상각·임의 접근이라는 적용 조건을 함께 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 정렬 배열의 탐색 구간을 중앙값 비교로 반씩 좁혀 값을 찾는 탐색 기법임
- 위치: (003 정렬이 만든 '정렬된 상태'를 입력 전제로 삼는 후속 탐색 단계임)
- 배경: 순차 탐색 O(N)은 데이터 폭증 시 선형으로 지연이 증가함
- 필요성: 대용량 인덱스·검색에서 log₂N 비교로 응답 시간을 상수급으로 억제할 수 있어 필수임

## Ⅱ. 구조 및 구성요소
선형 구조도 (구간 좁히기):

    정렬된 배열 + 목표값 -> low·high로 탐색 구간 설정 -> mid=(low+high)/2 비교
                                            / arr[mid] < 목표 : low = mid+1 (왼쪽 절반 배제)
                                            / arr[mid] > 목표 : high = mid-1 (오른쪽 절반 배제)
                                            / arr[mid] = 목표 : 탐색 성공

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정렬 배열 | 탐색 대상, 반씩 배제의 전제 | 미정렬 시 알고리즘 성립 불가 |
| low·high 포인터 | 남은 탐색 구간의 경계 | low > high면 탐색 실패(부재) |
| mid 인덱스 | 이번에 비교할 중앙 위치 | `low+(high-low)/2`로 오버플로 회피 |
| 비교 연산 | 목표와 대소 판정으로 방향 결정 | 3-way(< = >) 판정 |

> 요약: 정렬 배열 위에서 low·high·mid로 구간을 정하고, 대소 비교로 절반을 버리며 좁혀 감.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도:

    구간 설정(low=0, high=N-1) -> mid 계산 -> 목표와 비교 -> 절반 배제 후 구간 갱신 -> (반복) -> 성공/실패

1. 초기화: low=0, high=N-1로 전체를 탐색 구간으로 설정함
2. 중앙 비교: mid를 계산해 arr[mid]와 목표를 비교함
3. 구간 갱신: 목표가 크면 low=mid+1, 작으면 high=mid-1로 후보 절반을 배제함
4. 종료: 값이 일치하면 성공, low > high가 되면 부재로 실패 반환함

> 요약: 중앙 비교로 후보를 절반씩 버리는 2~3단계를 low>high까지 반복해 log₂N회에 종료함.

## Ⅳ. 특징
- 로그 시간: 매 비교마다 후보를 절반 배제해 O(log N)을 보장함 — 10억 건도 약 30회 비교임
- 정렬 종속: 정렬된 입력에서만 성립하며, 미정렬 데이터는 O(N log N) 정렬이 선행돼야 함
- 임의 접근 필수: mid로 한 번에 접근 가능한 배열에서만 유효하고, 연결 리스트에는 부적합함
- 낮은 부가 공간: 반복형 구현은 O(1) 추가 공간만 사용함(재귀형은 O(log N) 스택)

## Ⅴ. 심화 비교 및 적용 판단

정렬 전제·성능·자료구조 축에서 순차 탐색·해시 탐색과 대조함.

| 구분 | 이진 탐색 | 순차 탐색 | 해시 탐색(005) |
|:---|:---|:---|:---|
| 평균 시간 | O(log N) | O(N) | O(1) |
| 정렬 전제 | 필수 | 불필요 | 불필요 |
| 자료구조 | 정렬 배열(임의 접근) | 배열·리스트 무관 | 해시 테이블 |
| 범위 검색 | 가능(구간 조회 유리) | 가능 | 불가(등가 조회만) |

> 요약: 등가 조회 속도는 해시가 우세하나, 정렬 상태·범위 검색이 필요하면 이진 탐색이 적합함.

**리스크·대응:**
- 정렬 비용 미상각: 1회성 탐색에 정렬 O(N log N)을 쓰면 손해 → 탐색 빈도가 정렬 비용을 넘을 때만 채택
- mid 오버플로: `(low+high)/2`가 int 한계 초과 → `low+(high-low)/2`로 계산
- 잦은 삽입/삭제: 정렬 유지 비용 증가 → 동적 데이터는 이진 탐색 트리·B-Tree로 대체

**점검 지표:**
- 성능: 데이터 10배 증가 시 비교 횟수 증가폭 — log 추세 실측
- 정합성: 삽입 후 정렬 불변식 유지 여부 — 정렬 검증 테스트

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. DB 인덱스 탐색: B-Tree 인덱스 노드 내 정렬 키를 이진 탐색으로 O(log N) 조회해 Full Scan(O(N)) 회피
2. 경계값 탐색: `lower_bound`/`upper_bound`로 정렬 로그·시계열에서 특정 시각 이후 구간을 O(log N)에 절단
3. 파라메트릭 서치: "조건을 만족하는 최소 값" 최적화 문제를 단조성 위에서 이진 탐색으로 이분해 근사

**결론:**
- 기술사 판단: 정렬을 한 번 만들어 다회 탐색할 때 이진 탐색이 최적이며, 잦은 갱신 데이터는 B-Tree 계열로 확장해야 함
- 향후 방향: 대용량 분산 인덱스에서는 이진 탐색 원리를 계층화한 B⁺-Tree·LSM-Tree 인덱스로 디스크 I/O를 최소화하는 방향으로 진화 중임
