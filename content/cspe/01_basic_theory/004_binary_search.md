# 004. 이진 탐색 (Binary Search) [출제: ]

## 미리 알고가기

- **임의 접근 (Random Access)**: 인덱스를 통해 특정 메모리 위치에 즉시 접근하는 성질이며, 배열은 지원하지만 연결 리스트는 지원하지 않음
- **단조성 (Monotonicity)**: 데이터가 일정하게 증가하거나 감소하는 성질이며, 이진 탐색의 논리적 근거임
- **파라메트릭 서치 (Parametric Search)**: 최적화 문제(최대/최솟값 찾기)를 결정 문제(Yes/No)로 바꾸어 이진 탐색으로 해결하는 기법임

## Ⅰ. 개요

- **정의/개념**: 이진 탐색은 정렬된 데이터 집합에서 탐색 범위를 매 단계마다 절반으로 좁혀가며 목표 값을 찾는 $O(\log n)$ 복잡도의 검색 알고리즘임
- **배경/필요성**: 데이터가 백만 건 이상으로 늘어날 경우 선형 탐색($O(n)$)은 응답 지연을 초래함. 데이터가 정렬되어 있다는 전제하에 중앙값 비교만으로 나머지 절반을 탐색 대상에서 제외함으로써, 대규모 데이터에서의 검색 성능을 비약적으로 향상시킬 수 있음

## Ⅱ. 특징 및 비교

이진 탐색은 정렬을 전제로 하며, 검색 대상의 분포나 범위 검색 여부에 따라 선형 탐색, 해시 탐색과 차별화됨.

| 판단 기준 | 선형 탐색 (Linear) | 이진 탐색 (Binary) | 해시 탐색 (Hash) |
|:---|:---|:---|:---|
| 전제 조건 | 없음 (무작위 배치 가능) | **정렬 상태 + 임의 접근** | 해시 함수 및 테이블 확보 |
| 검색 복잡도 | $O(n)$ | $O(\log n)$ | $O(1)$ (평균) |
| 범위/근접 검색 | 처음부터 순회 필요 | **Lower/Upper Bound**로 지원 | 지원 불가 (동등 비교만 가능) |
| 장점 | 소량 데이터에 효율적 | 대량 데이터 검색에 최적 | 단일 건 검색 속도 최강 |
| 단점 | 데이터 증가 시 급격히 저하 | 삽입/삭제 시 정렬 유지 비용 | 해시 충돌 및 공간 낭비 발생 |

> 요약: 단일 건의 극단적 속도는 해시가 우위이나, 순서 유지와 범위 검색이 필요한 대규모 정적 데이터에는 이진 탐색이 최적임.

## Ⅲ. 구성요소/구조

이진 탐색은 $low$, $high$, $mid$ 세 개의 포인터를 조절하며 탐색 구간을 축소하는 원리로 동작함.

- **구성요소**:
  - **Low/High**: 현재 탐색 범위의 시작과 끝 인덱스
  - **Mid**: 탐색 구간의 정중앙 인덱스 ($low + (high - low) / 2$)
  - **Target**: 찾고자 하는 목표 값
  - **Decision Logic**: $mid$ 값과 $target$ 비교를 통한 구간 이동 결정

- **동작 원리 (절차)**:

```text
[초기 상태] low = 0, high = n-1
[단계 1] mid = (low + high) / 2 계산
[단계 2] 비교 수행:
          - A[mid] == Target : 탐색 성공, 인덱스 반환
          - A[mid] < Target  : low = mid + 1 (오른쪽 구간 선택)
          - A[mid] > Target  : high = mid - 1 (왼쪽 구간 선택)
[단계 3] low > high가 될 때까지 반복
```

1. **구간 설정**: 전체 배열을 대상으로 $low$와 $high$를 설정함
2. **중앙값 비교**: 중앙 위치의 원소가 목표값보다 큰지 작은지 판단함
3. **범위 축소**: 판단 결과에 따라 불필요한 절반의 데이터를 탐색 대상에서 즉시 제거함
4. **결과 반환**: 값을 찾으면 위치를 반환하고, 구간이 소진될 때까지 못 찾으면 실패를 반환함

## Ⅳ. 문제점 및 개선방안

1. **정렬 유지 비용의 발생**: 데이터가 빈번하게 삽입/삭제되는 환경에서는 매번 정렬을 수행해야 하므로 이진 탐색의 이점이 상쇄됨
   - **개선방안**: 동적 데이터 환경에서는 이진 탐색의 논리를 유지하면서도 삽입/삭제가 효율적인 **이진 탐색 트리(BST)** 또는 **B-Tree** 계열 자료구조를 활용함 (확인: 쓰기 대비 읽기 비율 분석)

2. **오버플로우 및 무한 루프 위험**: $(low + high) / 2$ 계산 시 두 변수의 합이 정수 범위를 넘거나, 경계 조건($low$, $high$ 업데이트) 미비로 구간이 줄어들지 않을 수 있음
   - **개선방안**: $low + (high - low) / 2$ 수식을 사용하여 오버플로우를 방지하고, 구간 종료 조건을 `while (low <= high)` 등으로 명확히 설정함 (확인: 경계값 테스트 케이스 검증)

3. **연결 리스트에서의 비효율성**: 연결 리스트는 인덱스를 통한 직접 접근이 불가능하여 중앙으로 가기 위해 $O(n)$ 순회가 필요하므로 이진 탐색의 의미가 퇴색됨
   - **개선방안**: 연결 리스트 구조에서 이진 탐색의 효율을 얻기 위해 **Skip List**를 도입하여 다층 인덱스 구조를 구축함 (확인: 자료구조별 접근 시간 측정)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터베이스 인덱스 | B-Tree 구조의 리프 노드에서 페이지 내의 레코드를 이진 탐색으로 조회 | 쿼리 응답 시간, Disk I/O 횟수 |
| 시스템 설정/룩업 테이블 | 부팅 시 로드되는 정적인 코드값 테이블에서 특정 키의 존재 여부를 고속 검색 | 메모리 사용량, 검색 지연 |
| 파라메트릭 서치 응용 | "네트워크 대역폭 $x$일 때 손실 없이 전송 가능한가?"를 만족하는 최대 $x$를 탐색 | 수렴 속도, 조건 판정 함수 비용 |
| 소프트웨어 디버깅 | 소스 코드의 특정 버전부터 오류가 발생했는지 찾기 위해 커밋 내역을 이진 탐색 (git bisect) | 오류 원인 커밋 식별 시간 |

> 요약: 정렬된 정적 데이터 검색뿐만 아니라, 답의 범위 내에서 최적값을 찾는 결정 문제 해결에 광범위하게 활용됨.

## Ⅵ. 결론

이진 탐색은 $O(\log n)$이라는 강력한 성능을 바탕으로 대규모 데이터 처리 시스템의 근간을 이루는 알고리즘임. 기술사는 이진 탐색을 단순히 검색 기법으로만 보지 않고, 데이터의 단조성을 활용하여 복잡한 최적화 문제를 해결하는 "파라메트릭 서치"로 확장 적용할 수 있는 능력을 갖추어야 함.

또한, 실무 적용 시에는 데이터의 변경 빈도와 접근 패턴을 분석하여 정렬 배열 기반의 이진 탐색을 쓸 것인지, 아니면 이를 구조화한 인덱스 트리(B-Tree)를 선택할 것인지에 대한 아키텍처적 의사결정이 필요함. 결국 이진 탐색의 핵심은 "불필요한 정보를 얼마나 빠르게 소거하느냐"에 있으며, 이는 효율적인 시스템 설계의 보편적 원리와 닿아 있음.
