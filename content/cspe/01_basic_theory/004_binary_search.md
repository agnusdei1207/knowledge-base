## Ⅰ. 개요

- **정의**: 이진 탐색(Binary Search)은 정렬된 배열에서 중간값과 목표값을 비교해 매 단계 탐색 범위를 절반으로 줄이는 탐색 알고리즘임.
- **배경/필요성**: 정렬된 데이터라도 첫 원소부터 순차 비교하는 선형 탐색은 원소 수에 비례해 비교 횟수가 늘어나므로, 정렬되어 있다는 성질을 활용해 비교 1회마다 남은 탐색 범위를 절반씩 제거하는 방법이 필요함.
- **출제 의도**: 정렬 전제 조건의 이해, `low`/`high`/`mid` 경계 갱신의 정확한 구현력, Lower/Upper Bound·이분 결정 등 변형 응용력을 확인함.
- **답안 방향**: 구조(경계 변수 3요소) → 동작(범위 축소 3단계 + 경계 처리 버그) → 비교(선형 탐색·해시 테이블 대비 적용 조건) → 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정렬 전제 하 탐색 구조 설명 요구 | 정렬 전제 조건, `low`/`high`/`mid` 경계 갱신, $O(\log N)$ 도출 근거 | 정렬 전제 누락, 경계 갱신 오류 방치, 비교 대상 없이 장점만 나열 |

> 요약: 이진 탐색 답안은 정렬 전제와 경계 처리 정확성을 먼저 못 박고, 그 위에서 선형 탐색 대비 이득을 논증해야 함.

## Ⅱ. 구조 및 구성요소

```text
배열(정렬됨): [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], target=23

1단계: low=0, high=9, mid=4 -> A[4]=16 < 23 -> low=5
2단계: low=5, high=9, mid=7 -> A[7]=56 > 23 -> high=6
3단계: low=5, high=6, mid=5 -> A[5]=23 == 23 -> 발견, 인덱스 5 반환

비교 횟수 3회 (동일 배열에서 선형 탐색은 최대 6회 필요)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| `low`, `high` | 현재 탐색 범위의 양 끝 인덱스 추적 | 사전에서 남은 페이지의 좌우 경계 |
| `mid` | `low + (high - low) / 2`로 다음 비교 지점 산출 | 사전을 정확히 반으로 펴기 |
| 비교 연산 | `A[mid]`와 target의 대소를 비교해 방향 결정 | "더 높아/더 낮아" 판정 |
| 종료 조건 | `low > high`이면 탐색 실패로 확정 | 두 경계가 서로 교차하면 "없음" |

> 요약: `low`/`high`가 범위를, `mid` 계산이 다음 비교 지점을, 비교 연산과 종료 조건이 각각 방향 결정과 실패 판정을 담당함.

## Ⅲ. 동작원리 및 흐름도

```text
탐색 시작(low=0, high=N-1) -> mid 계산 -> A[mid]와 target 비교
  -> 같음: 인덱스 반환(종료)
  -> A[mid] < target: low = mid + 1
  -> A[mid] > target: high = mid - 1
-> low > high면 실패 반환, 아니면 mid 재계산으로 반복
```

- 1단계(범위 초기화): `low=0`, `high=N-1`로 탐색 전체 범위를 설정함.
- 2단계(중간값 비교): `mid = low + (high - low) / 2`를 계산하고 `A[mid]`와 target을 비교함.
- 3단계(범위 축소): 비교 결과에 따라 `low = mid + 1` 또는 `high = mid - 1`로 범위를 절반으로 줄임.
- 4단계(종료 판정): `A[mid] == target`이면 발견, `low > high`이면 탐색 실패로 종료함. 이 경계 갱신을 잘못 구현하면 아래 세 가지 버그가 반복적으로 발생함.
  1. 정수 오버플로우: `mid = (low + high) / 2`는 `low + high`가 표현 범위를 넘으면 오동작하므로 `mid = low + (high - low) / 2`로 계산함.
  2. `high` 경계 정체: `high = mid`로 갱신하면 `low == high == mid` 경계에서 범위가 줄지 않아 무한 루프에 빠지므로 `high = mid - 1`로 갱신함.
  3. `low` 경계 정체: 대칭적으로 `low = mid`로 갱신하면 이미 비교를 마친 `mid`가 범위에 남으므로 `low = mid + 1`로 갱신함.

> 요약: `mid` 계산과 경계 갱신(`low=mid+1`/`high=mid-1`)이 매 반복마다 범위를 절반으로 줄이며, 이 규칙을 어기면 무한 루프나 오탐이 발생함.

## Ⅳ. 특징

- 탐색 성능: 비교 1회마다 범위가 절반으로 줄어 $O(\log N)$ 성능을 보장함. $N$이 10억이어도 최대 30회 비교로 종료함.
- 전제 조건: 배열이 정렬되어 있어야 성립하며, 비정렬 배열에 적용하면 런타임 오류 없이 잘못된 결과를 반환함.
- 구현 난이도: 원리는 단순하나 `mid` 계산·`low`/`high` 갱신을 잘못 구현하면 오작동하기 쉬워, 표준 패턴을 고정해 적용하는 것이 실무상 중요함.
- 확장성: 비교 조건과 반환값 정의만 바꾸면 Lower Bound(target 이상인 첫 위치)·Upper Bound(target 초과인 첫 위치)·이분 결정(조건을 만족하는 최적값 탐색)으로 응용됨.

> 요약: $O(\log N)$ 성능은 정렬 전제와 정확한 경계 처리라는 두 조건이 함께 충족될 때만 성립함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 기준 | 이진 탐색 | 선형 탐색 | 선택 기준 |
|:---|:---|:---|:---|
| 전제 조건 | 정렬 필수 | 없음 | 데이터가 비정렬이고 1회성 탐색이면 정렬 비용이 손해 |
| 시간 복잡도 | $O(\log N)$ | $O(N)$ | 동일 데이터에 대한 탐색이 반복될수록 이진 탐색 유리 |
| 삽입·삭제 빈도 | 배열 삽입 시 $O(N)$ 시프트 | 삽입 $O(1)$ | 삽입·삭제가 잦으면 BST·해시 테이블(005) 등 동적 구조 검토 |

> 요약: 정렬 비용을 상쇄할 만큼 탐색이 반복되고 데이터 변경이 적을 때만 이진 탐색이 선형 탐색보다 유리하며, 삽입·삭제가 잦으면 해시 테이블 등 다른 구조와 비교해야 함.

**리스크·대응 (불릿):**
- 경계 처리 오류: `mid` 계산·`low`/`high` 갱신 규칙 미준수가 원인 → 표준 패턴 준수를 코드 리뷰 체크리스트에 고정해 대응함.
- 정렬 전제 붕괴: 탐색 도중 배열에 원소가 삽입·삭제되어 정렬 상태가 깨지는 것이 원인 → 탐색용 스냅샷 고정 또는 삽입 시 재정렬 트리거로 대응함.

**도입 후 점검 지표 (불릿):**
- 정확성: 첫/마지막 원소·target 부재 등 경계값 케이스의 단위 테스트 통과 여부로 확인함.
- 성능: 최악 비교 횟수가 이론값 $\lceil \log_2 N \rceil$ 이내인지 실측으로 확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 정렬 여부와 탐색 반복 빈도를 점검해 이진 탐색 적용 대상을 식별함.
2. 중기: `low`/`high`/`mid` 표준 패턴과 Lower/Upper Bound 유틸리티를 공용 라이브러리로 정리해 재사용함.
3. 장기: 데이터 변경 빈도가 높아지면 BST·B-Tree 등 동적 구조로 전환하는 기준을 운영 정책에 반영함.

- 기술사적 판단: 정렬 비용 대비 반복 탐색으로 얻는 이득이 클 때만 이진 탐색을 선택함.
- 기술사 제언: 경계 처리 표준 패턴을 코드 리뷰 체크리스트에 명시해 반복되는 구현 오류를 예방함.
