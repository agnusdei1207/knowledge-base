## Ⅰ. 개요
- **정의**: 정렬된 배열에서 중간값과 대상을 비교하여 탐색 범위를 절반씩 축소하는 `O(log n)` 탐색 알고리즘
- **배경/필요성**: 선형 탐색 `O(n)`으로는 대규모 정렬 데이터에서 응답 시간 요구를 충족하기 어려움
- **비유**: 사전에서 단어를 찾을 때 중간 페이지를 펴고 앞/뒤를 판단하여 절반씩 좁혀 가는 방식과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 분할 탐색 원리와 변형 적용 | 전제 조건=정렬 완료, 매 비교마다 범위 1/2 축소 | `low`, `high` 경계 갱신 시 off-by-one 오류 주의 |

> 요약: 정렬된 데이터에서 중간값 비교로 탐색 범위를 절반씩 줄여 `O(log n)`에 탐색하는 기법임

## Ⅱ. 구성요소
```text
        +--- 정렬 배열 --- 탐색 전제 조건
        |
  이진 탐색 --+--- 경계 포인터 --- low / high / mid
        |
        +--- 비교 로직 --- target vs arr[mid]
        |
        +--- 변형 --- lower bound / upper bound / parametric search
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정렬 배열 | 오름차순으로 정렬이 완료된 입력 데이터 | 가나다순 전화번호부 |
| 경계 포인터 | `low`=탐색 시작, `high`=탐색 끝, `mid`=중간 인덱스 | 책의 첫 페이지·끝 페이지·중간 페이지 |
| 비교 로직 | `target < arr[mid]`이면 `high = mid - 1`, 크면 `low = mid + 1` | 사전 단어가 앞인지 뒤인지 판단 |
| 변형 기법 | lower/upper bound(경계값 탐색), parametric search(최적값 이분 판정) | 합격선 찾기(경계), 최적 온도 탐색(판정) |

> 요약: 정렬 배열 위에서 경계 포인터와 비교 로직으로 탐색 범위를 반복 축소하는 구조임

## Ⅲ. 절차
```text
  초기화             중간값 계산        비교 판정          범위 갱신
  (low=0,high=n-1)  (mid 산출)        (target vs mid)   (low/high 이동)
   |                 |                 |                 |
   +----설정-------->+----계산-------->+----판정-------->+
  전체 범위 설정    (low+high)/2      일치/좌측/우측     범위 절반 축소
                         ^                               |
                         +----------반복(low<=high)-------+
```
- 1단계: `low = 0`, `high = n - 1`로 전체 배열 범위를 초기화함
- 2단계: `mid = (low + high) / 2`로 중간 인덱스를 계산함 — 오버플로 방지 시 `low + (high - low) / 2` 사용
- 3단계: `target`과 `arr[mid]`를 비교함 — 일치하면 반환, 작으면 좌측, 크면 우측으로 판정
- 4단계: 판정 결과에 따라 `high = mid - 1` 또는 `low = mid + 1`로 범위를 갱신하고 2단계로 반복

> 요약: 초기화 → 중간값 계산 → 비교 판정 → 범위 갱신을 `low <= high`인 동안 반복함

## Ⅳ. 문제점
- 정렬 전제 의존: 입력이 미정렬 상태이면 사전 정렬 비용 `O(n log n)`이 추가로 발생함
- 경계 오류 빈발: `low`, `high`, `mid` 갱신에서 off-by-one 실수가 발생하면 무한 루프 또는 누락이 생김
- 동적 데이터 부적합: 삽입·삭제가 빈번한 데이터에서는 매번 재정렬이 필요하여 유지 비용이 큼

> 요약: 정렬 전제, 경계 갱신 오류, 동적 데이터 비적합이 이진 탐색의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 삽입 시 정렬 상태를 유지하는 자료구조(정렬 배열, BST)를 사용하여 사전 정렬 비용을 제거함
2. 중기: lower/upper bound 템플릿을 표준화하여 경계 갱신 오류를 구조적으로 방지함
3. 장기: 균형 이진 탐색 트리(AVL, Red-Black)나 B-Tree를 도입하여 동적 삽입·삭제와 `O(log n)` 탐색을 동시 지원함

> 요약: 정렬 유지 자료구조, 표준 템플릿, 균형 트리 도입으로 이진 탐색의 제약을 해소함

## Ⅵ. 전망
- 발전 방향: parametric search가 최적화 문제에 확대 적용되며, 분산 환경에서의 이분 판정 기법도 활용됨
- 기술사적 판단: `O(log n)` 탐색은 DB 인덱스, 네트워크 라우팅 등 실무 전반의 기반 기법임
- 기술사 제언: 단순 배열 탐색을 넘어 결정 문제에 이진 탐색을 적용하는 사고 확장이 필요
