# 📖 【암기용】 개념 완전 이해

> 목적: 이진 탐색을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 정렬된 데이터에서 탐색 범위를 절반씩 줄이는 알고리즘
- **왜 필요한가**: 순차 탐색은 n개를 차례로 확인하지만, 이진 탐색은 비교 1회마다 후보 절반을 제거한다. 대규모 정렬 데이터의 조회 비용을 O(log n)으로 낮춘다.
- **핵심 직관**: 정렬이라는 전제 덕분에 "왼쪽 또는 오른쪽 절반은 볼 필요 없음"을 반복하는 방식임

## 깊이 이해
- **배경·문제의식**: 회원 ID 1억건에서 순차 탐색은 최악 1억회 비교가 필요하다. 정렬 배열이면 log2(1억)≈27회 비교로 존재 여부를 판단한다.
- **작동 원리**: low와 high를 두고 mid를 계산한다. target이 arr[mid]보다 작으면 high=mid-1, 크면 low=mid+1로 갱신한다. low>high면 부재로 종료한다.
- **비유**: 사전에서 단어를 찾을 때 첫 장부터 넘기지 않고 가운데를 열어 앞쪽/뒤쪽 절반을 버리는 방식이다.
- **구체 예시**: n=1,024이면 최대 10회 비교, n=1,048,576이면 최대 20회 비교. 정렬 비용 O(n log n)을 이미 지불했거나 여러 번 조회할 때 효과가 큼.
- **흔한 오해·주의점**: 정렬되지 않은 배열에는 적용할 수 없다. 또한 `(low+high)/2`는 정수 오버플로우 가능성이 있어 `low+(high-low)/2` 권장.

## 연결 개념
- 정렬 알고리즘 — 이진 탐색의 선행 조건
- B-Tree 인덱스 — 디스크 블록 단위 다분 탐색
- Lower/Upper Bound — 중복 키 범위 탐색

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이진 탐색은 정렬된 순차 접근 구조에서 중앙값 비교로 탐색 구간을 절반씩 축소하는 O(log n) 탐색 알고리즘이다.
> 2. **가치**: n=10^8에서도 최악 비교 횟수 약 27회로 존재 여부·삽입 위치·경계 값을 산정한다.
> 3. **판단 포인트**: 정렬 전제, 랜덤 접근 가능성, 중복 키 처리, 오버플로우 방지, 경계 조건 검증이 필수임.

## Ⅰ. 개요 및 필요성

개요: 정렬 배열의 절반 축소 탐색이다. 대량 데이터 조회에서 순차 탐색 O(n)은 응답 지연을 키운다. 이진 탐색은 정렬·랜덤 접근 조건을 만족할 때 O(log n) 비교로 검색·삽입 위치·범위 질의를 처리함.

## Ⅱ. 구조 및 구성요소

```text
┌──────────┐   low ─── mid ─── high
│ 정렬 배열 │──────▶ target 비교
└──────────┘          │ 작음/큼
                      ▼
                 구간 절반 축소
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정렬 배열 | 탐색 대상 | 오름차순·내림차순 기준 일관성 |
| low/high | 현재 탐색 구간 경계 | low≤high 유지 |
| mid | 중앙 비교 위치 | low+(high-low)/2 |
| target | 찾을 키 | 중복 시 lower/upper bound 필요 |

> 요약: 이진 탐색은 정렬 배열, 좌우 경계, 중앙 위치, 목표 키의 비교 관계로 구간을 갱신함.

## Ⅲ. 동작원리 및 흐름도

```text
low=0, high=n-1 → mid 계산 → arr[mid]와 target 비교
               → 같음: 반환
               → 작음: high=mid-1
               → 큼: low=mid+1
               → low>high: 부재
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 정렬 여부 확인 | key[i]≤key[i+1] |
| 2 | low/high 초기화 | 0, n-1 |
| 3 | mid 비교 | 오버플로우 방지식 |
| 4 | 탐색 구간 갱신 | 절반 축소 불변식 |
| 5 | 종료 판정 | 발견 인덱스 또는 -1 |

> 요약: 중앙 비교 후 한쪽 구간을 제거하는 과정을 low>high 또는 target 발견까지 반복함.

## Ⅳ. 특징

| 구분 | 이진 탐색 | 순차 탐색 | 수치 기준 |
|:---|:---|:---|:---|
| 전제 | 정렬·랜덤 접근 | 전제 없음 | 배열 인덱스 O(1) |
| 시간복잡도 | O(log n) | O(n) | n=10^6, 20회 vs 최대 10^6회 |
| 공간복잡도 | 반복 O(1), 재귀 O(log n) | O(1) | 재귀 스택 깊이 log2 n |
| 한계 | 삽입·삭제 O(n) | 정렬 비용 없음 | 배열 중간 삽입 시 이동 n/2 |

> 요약: 이진 탐색은 조회 중심 정렬 배열에 적합하며, 빈번한 삽입·삭제는 트리·해시 구조 검토 필요.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 검색 API: 정렬된 메모리 배열에서 SKU·ID 조회를 O(log n)으로 처리, 중복 키는 lower_bound/upper_bound로 범위 산정
2. DB/파일 처리: B-Tree·SSTable sparse index에서 블록 위치 후보를 좁힌 뒤 블록 내부 이진 탐색 적용
3. 검증 자동화: 빈 배열, 1개 원소, 첫/끝 원소, 부재 값, 중복 값 테스트 케이스를 CI에 포함

**결론 (2줄):**
- 기술사 판단: 읽기 빈도 높고 정렬 유지 비용을 감당할 수 있으면 이진 탐색, 쓰기 빈도 높으면 균형트리·해시를 선택함
- 향후 방향: SIMD·branchless binary search와 cache-aware layout으로 CPU 분기 실패·캐시 미스를 줄이는 구현 확대 필요
