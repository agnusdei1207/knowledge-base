# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 재귀 알고리즘은 함수가 자기 자신을 호출하여 문제를 작게 쪼개어 푸는 기법이며, 마스터 정리는 이런 재귀 알고리즘의 시간 복잡도를 공식 하나로 3초 만에 구하는 마법의 공식이다.
- **왜 필요한가**: 분할 정복 알고리즘(예: 병합 정렬)을 설계할 때, 이 알고리즘이 얼마나 빠른지 일일이 재귀 트리를 그려가며 증명하는 것은 너무 오래 걸리므로 필요하다.
- **핵심 직관**: 문제를 "몇 개로 쪼개는지(a)", "얼마나 작게 쪼개는지(b)", "합치는 데 드는 비용은 얼마인지(O(n^d))" 세 가지 변수의 힘겨루기(가중치)로 전체 시간을 결정한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 재귀 관계식 | $T(n) = aT(n/b) + O(n^d)$ | "문제를 a개로 나누고, 크기는 1/b로 줄이고, 합치는 데 n^d만큼 쓴다" |
| 파생 문제 수 ($a$) | 한 번 분할할 때 생기는 하위 문제의 개수 ($a \ge 1$) | 병합 정렬은 반씩 2개로 나누므로 $a=2$ |
| 분할 비율 ($b$) | 입력 크기가 줄어드는 비율 ($b > 1$) | 반으로 나누므로 크기는 1/2이 됨, 즉 $b=2$ |
| 임계 지수 ($\log_b a$) | 하위 문제들이 분할되면서 늘어나는 작업량의 지표 | "문제가 증식하는 속도" |

## 깊이 이해
- **배경·문제의식**: $T(n) = 2T(n/2) + O(n)$ (병합 정렬)의 복잡도는 수학적 귀납법이나 재귀 트리로 증명하면 $O(n \log n)$이 나온다. 하지만 실무에서 알고리즘을 짤 때마다 이런 긴 증명을 할 수 없다.
- **작동 원리**: 마스터 정리는 $n^d$(문제를 쪼개고 합치는 비용)와 $n^{\log_b a}$(하위 문제를 푸는 총비용) 중 **누가 더 무거운지** 비교하여 승자를 전체 복잡도로 취한다.
  - **Case 1 (하위 문제가 무거움)**: $d < \log_b a$ → $O(n^{\log_b a})$. 예: $T(n) = 4T(n/2) + n$ → $1 < \log_2 4 = 2$ 이므로 $O(n^2)$.
  - **Case 2 (둘이 비슷함)**: $d = \log_b a$ → 승부가 안 나므로 로그를 곱해줌 → $O(n^d \log n)$. 예: $T(n) = 2T(n/2) + n$ → $1 = \log_2 2 = 1$ 이므로 $O(n \log n)$.
  - **Case 3 (합치는 비용이 무거움)**: $d > \log_b a$ → $O(n^d)$. 예: $T(n) = 2T(n/2) + n^2$ → $2 > \log_2 2 = 1$ 이므로 $O(n^2)$.
- **비유**: a는 "하청업체를 늘리는 속도", b는 "하청에 넘기는 업무량 축소 비율", d는 "원청이 취합하는 비용"이다. 하청이 너무 많아지면(Case 1) 하청 비용이 전체를 지배하고, 취합이 너무 빡세면(Case 3) 원청 취합 비용이 지배한다. 균형이 맞으면(Case 2) 로그를 붙여 합산한다.
- **구체 예시**: 이진 탐색은 $T(n) = 1T(n/2) + O(1)$. $a=1, b=2, d=0$. $\log_2 1 = 0 = d$. (Case 2). 따라서 $O(\log n)$.
- **흔한 오해·주의점**: 마스터 정리는 모든 재귀식에 통하지 않는다. 분할 비율 $b$가 상수가 아니거나(예: $T(n) = T(n-1)$), $O(n^d)$ 부분이 다항식이 아닌 로그 형태면 마스터 정리 기본형을 곧바로 적용할 수 없다.

## 연결 개념
- (014) 분할 정복 — 마스터 정리가 가장 많이 쓰이는 알고리즘 설계 패러다임
- (001) 시간 복잡도 — 분석의 최종 목표

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 마스터 정리는 $T(n) = aT(n/b) + f(n)$ 형태의 재귀 알고리즘 시간 복잡도를 점근적으로 즉시 도출하는 수학적 공식이다.
> 2. **가치**: 재귀 트리나 점화식을 매번 전개할 필요 없이, 분할(a, b) 비용과 병합(f(n)) 비용의 가중치 비교만으로 복잡도를 확정할 수 있다.
> 3. **판단 포인트**: 알고리즘 설계 시 분할 개수(a)를 줄이거나 병합 비용(d)을 낮춰 마스터 정리의 Case를 낮은 차수로 이동시키는 것이 최적화의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 재귀 관계식 구성과 점근적 표기법 도출 역량 | $aT(n/b) + O(n^d)$ 수식과 $d$ vs $\log_b a$ 3가지 Case 비교 | 수식 없이 말로만 설명, Case 1/2/3의 대소 관계 부호 오류 |
| 알고리즘 적용 사례 연결 | 병합 정렬(Case 2), 이진 탐색(Case 2), 행렬 곱(Case 1) 등 실제 사례 매핑 | 억지 수치 나열, 적용 불가능한 조건(선형 감소 등) 누락 |

> 요약: 마스터 정리는 분할 정복 비용과 병합 비용의 크기 비교(3가지 Case)를 수식으로 정확히 제시하고 실제 알고리즘에 매핑해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 분할 정복(Divide and Conquer) 등 재귀적으로 호출되는 알고리즘의 수행 시간 $T(n)$을 직관적인 공식으로 계산하는 정리
- 배경: 재귀 트리를 그리거나 치환법(Substitution Method)으로 점화식을 푸는 과정은 시간과 검증 비용이 과다하게 소요됨
- 필요성: 알고리즘 설계 초기 단계에서 $a, b, d$ 파라미터 조정만으로 최종 시간 복잡도 $O(N)$을 즉시 확정하고 성능을 예측하기 위해 필수

---

## Ⅱ. 구조 및 구성요소

```text
점화식 구조: T(n) = a * T(n / b) + f(n)
             |          |         |
             +-> 분할 수  |         +-> 분할·병합 비용 O(n^d)
                        +-> 크기 축소율
```

| 변수 | 의미 | 조건 |
|:---|:---|:---|
| $a$ | 하위 문제(Sub-problem)로 분할되는 개수 | $a \ge 1$ (상수) |
| $b$ | 입력 데이터 $n$이 분할될 때 줄어드는 비율 | $b > 1$ (상수) |
| $f(n)$ | 하위 문제로 분할하고 결과를 병합하는 데 드는 비용 | 다항식 $O(n^d), d \ge 0$ |

> 요약: 마스터 정리는 잎 노드(재귀의 끝) 연산량 $O(n^{\log_b a})$와 내부 노드 병합 연산량 $O(n^d)$의 힘겨루기로 전체 복잡도를 결정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
재귀식 T(n) 추출 -> a, b, d 값 식별 -> 임계 지수(log_b a) 계산
-> d 와 log_b a 크기 비교 (3개 Case) -> 최종 점근적 표기(Big-O) 확정
```

- 1단계 [점화식 추출]: 분석 대상 알고리즘의 루프와 재귀 호출을 $T(n) = aT(n/b) + O(n^d)$ 형태로 모델링
- 2단계 [상수 식별]: 분할 개수 $a$, 축소 비율 $b$, 분할/병합 다항식 차수 $d$ 도출
- 3단계 [크기 비교]: 병합 비용 지수 $d$ 와 분할 증식 지수 $\log_b a$ 의 대소 관계 판별
- 4단계 [Case 적용]: 3가지 Case 중 하나를 적용하여 최종 $O(\dots)$ 결정

> 요약: 알고리즘의 구조에서 상수를 뽑아낸 뒤, 단 한 번의 대소 비교 연산으로 전체 복잡도를 산출한다.

---

## Ⅳ. 심화 비교 및 적용 판단

| Case | 조건 (비용 승패) | 최종 복잡도 $T(n)$ | 실제 적용 알고리즘 사례 |
|:---|:---|:---|:---|
| Case 1 | $d < \log_b a$ (분할 비용 지배) | $\Theta(n^{\log_b a})$ | 슈트라센 행렬 곱 ($a=7, b=2, d=2$) → $O(n^{\log_2 7})$ |
| Case 2 | $d = \log_b a$ (비용 균형) | $\Theta(n^d \log n)$ | 병합 정렬 ($a=2, b=2, d=1$) → $O(n \log n)$ |
| Case 3 | $d > \log_b a$ (병합 비용 지배) | $\Theta(n^d)$ | (비효율적 재귀) $T(n) = 2T(n/2) + O(n^2)$ → $O(n^2)$ |

> 요약: 비용을 더 많이 차지하는 쪽(분할 vs 병합)이 전체 복잡도를 지배하며, 같을 때는 트리의 높이($\log n$)를 곱해 보정한다.

**리스크·대응:**
- [마스터 정리 적용 불가 케이스]: $T(n) = T(n-1) + O(1)$ 처럼 비율($b$)이 아닌 상수로 감소하는 재귀 → 치환법이나 재귀 트리 활용 (지표: $b>1$ 조건 검증)
- [비다항식 병합 비용]: $f(n) = O(n \log n)$ 등 다항식이 아닌 경우 기본 마스터 정리(3 Case) 적용 불가 → 확장 마스터 정리(Akra-Bazzi method) 적용

**도입 후 점검 지표:**
- 성능/효율: 알고리즘 병목 구간 진단 — $a$를 줄일 것인지 $d$를 줄일 것인지 의사결정
- 품질/운영: 분할 정복 설계 시 재귀 호출 깊이(Depth) — $O(\log_b n)$ 한계 도달로 인한 스택 오버플로우 점검

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. [알고리즘 최적화 설계]: Case 1 영역에 있는 알고리즘은 분할 호출 횟수($a$)를 줄이는 수학적 기법(예: 카라추바 곱셈)을 적용해 차수 강하 수행
2. [병합 비용 최적화]: Case 3 영역에서는 병합 작업 $f(n)$을 단순화하여 $d$를 낮추는 해시 맵 적용 등으로 복잡도 등급 하향 조정
3. [재귀 제거 적용]: 시간 복잡도가 적정하더라도 공간 복잡도(Call Stack)가 문제 될 시, Tail Recursion 최적화나 반복문(Iteration)으로 전환 구현

**결론:**
- 기술사 판단: 마스터 정리는 단순한 수학 공식이 아니라, 분할 정복 설계 시 "재귀를 적게 할 것인가(a 감소)" vs "빠르게 합칠 것인가(d 감소)"를 결정하는 아키텍처 판단 지표다.
- 향후 방향: 현대 시스템에서는 멀티 코어 환경을 고려하여 병렬 마스터 정리(Work-Span 모델)를 적용한 병렬 분할 정복(Parallel Divide & Conquer)으로 분석 체계가 확장되고 있다.
