# 📖 【암기용】 개념 완전 이해

> 목적: 해밍 코드와 오류 검출·정정을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 비트에 패리티 비트를 추가해 1비트 오류 위치를 찾아 정정하는 코드
- **왜 필요한가**: 메모리, 저장장치, 통신 채널은 전기적 노이즈와 셀 오류로 비트가 뒤집힐 수 있어 검출·정정 체계가 필요하다.
- **핵심 직관**: 여러 개의 패리티 검문소가 같은 오류 비트를 가리키면 그 위치를 찾아 뒤집는다.

## 깊이 이해
- **배경·문제의식**: 단순 패리티는 오류 존재만 알 수 있고 위치는 찾지 못한다. 해밍 코드는 패리티 검사 결과를 이진수 위치값으로 해석해 오류 비트를 식별한다.
- **작동 원리**: 패리티 비트는 1,2,4,8번처럼 2의 거듭제곱 위치에 둔다. 검사 결과 syndrome이 0이면 오류 없음, 0이 아니면 해당 위치 비트를 반전한다.
- **비유**: 창고 물품에 여러 구역 표식을 붙여 두면 분실 위치를 교차 확인으로 찾는 방식과 같다.
- **구체 예시**: Hamming(7,4)는 데이터 4비트에 패리티 3비트를 추가한다. syndrome이 `101₂=5`이면 5번 비트를 뒤집는다.
- **흔한 오해·주의점**: 기본 해밍 코드는 1비트 오류 정정만 가능하다. SECDED는 전체 패리티를 추가해 2비트 오류를 검출하지만 정정하지는 못한다.

## 연결 개념
- 패리티 검사 — 오류 검출의 최소 단위
- ECC 메모리 — SECDED 기반 DRAM 오류 대응
- CRC — 블록 오류 검출에 특화된 다항식 기반 코드


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 해밍 코드는 패리티 비트를 2의 거듭제곱 위치에 배치해 syndrome으로 오류 위치를 찾는 선형 블록 코드이다.
> 2. **가치**: Hamming(7,4)는 4비트 데이터에 3비트 패리티를 추가해 1비트 오류를 검출·정정한다.
> 3. **판단 포인트**: 단순 패리티, 해밍, SECDED, CRC는 오류 위치 식별과 정정 가능 범위가 다르다.


## Ⅰ. 개요 및 필요성

해밍 코드는 1비트 오류 정정을 위한 ECC 기법이다.  
메모리와 통신 채널의 비트 오류는 프로그램 오동작과 데이터 손상을 유발한다.  
해밍 코드는 패리티 검사 결과인 syndrome으로 오류 위치를 산출해 재전송 없이 1비트 오류를 복구한다.


## Ⅱ. 구조 및 구성요소

```text
┌──────────┐   ┌────────────┐   ┌────────────┐
│ 데이터비트 │──▶│ 패리티 삽입 │──▶│ 코드워드    │
└──────────┘   └─────┬──────┘   └─────┬──────┘
                     │ 1,2,4 위치     │
                     ▼                ▼
                syndrome 계산      오류 위치
```

| 구성요소 | 역할 | 수치 기준 |
|:---|:---|:---|
| 데이터 비트(k) | 실제 전송·저장 정보 | Hamming(7,4)의 k=4 |
| 패리티 비트(r) | 검사 집합별 짝/홀수 패리티 저장 | `2^r >= k+r+1` |
| 코드워드(n) | 데이터+패리티 전체 비트열 | n=k+r, 예: 7비트 |
| Syndrome | 패리티 재계산 결과 | 0=오류 없음, 비0=오류 위치 |

> 요약: 해밍 코드는 데이터, 패리티, 코드워드, syndrome의 조합으로 1비트 오류 위치를 산출한다.


## Ⅲ. 동작원리 및 흐름도

```text
데이터 입력 → 패리티 위치 확보 → 패리티 계산 → 코드워드 전송/저장
       → 수신 후 재계산 → syndrome 생성 → 오류 비트 반전
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 패리티 비트 수 r 결정 | `2^r >= k+r+1` |
| 2 | 1,2,4,8 위치에 패리티 배치 | 2의 거듭제곱 위치 |
| 3 | 수신 코드워드에서 패리티 재계산 | 검사 집합별 XOR |
| 4 | syndrome 값으로 오류 위치 정정 | syndrome=5이면 5번 비트 반전 |

> 요약: 패리티 검사 결과를 이진 위치값으로 해석해 syndrome이 가리키는 비트를 반전하는 방식이다.


## Ⅳ. 특징

| 구분 | 단순 패리티 | 해밍 코드 | SECDED |
|:---|:---|:---|:---|
| 검출 범위 | 홀수 개 오류 검출 | 1비트 오류 검출 | 1비트 정정, 2비트 검출 |
| 정정 범위 | 정정 불가 | 1비트 정정 | 1비트 정정 |
| 추가 비트 | 1비트 | r비트, `2^r >= k+r+1` | r+1비트 |
| 적용 영역 | 저비용 링크 | 기본 ECC | 서버 DRAM ECC |

> 요약: 해밍 코드는 단순 패리티보다 오류 위치 식별이 가능하고, SECDED는 전체 패리티로 2비트 오류 검출 범위를 추가한다.


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. ECC 메모리: 64비트 데이터에 8비트 ECC를 붙인 SECDED 구성으로 1비트 오류 자동 정정
2. 저장장치 검증: NAND Flash는 BCH/LDPC, 저비용 제어 메모리는 Hamming 계열 선택
3. 통신 프로토콜: 오류 정정은 FEC, 블록 무결성 검출은 CRC-32를 병행 적용

**결론 (2줄):**
- 기술사 판단: 단일 비트 soft error가 주 위험이면 SECDED, burst error가 주 위험이면 CRC+BCH/LDPC를 선택함
- 향후 방향: 고집적 메모리는 rowhammer·방사선 soft error 대응을 위해 ECC scrubbing과 patrol read를 병행함
