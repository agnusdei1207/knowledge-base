## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 데이터 전송 중 발생하는 단일 비트 오류를 스스로 검출하고 정정(FEC)할 수 있는 선형 블록 코드임 |
| 배경/필요성 | 메모리나 통신 채널의 잡음으로 인한 데이터 손상을 막고 신뢰성 있는 정보 교환을 보장하기 위해 필요함 |
| 출제 의도 | 패리티 비트의 원리, 해밍 거리(Hamming Distance) 개념 및 오류 정정 메커니즘 이해 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|   Data Bits       | ----> |  Parity Bits      | ----> |  Syndrome Vector  |
|   (Message)       |       |  (Error check)    |       |  (Error locator)  |
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 데이터 비트 | 전송하고자 하는 실제 유효 정보 | 소포 내용물 |
| 패리티 비트 | 2^n 번째 위치에 삽입되어 특정 데이터 비트 그룹의 짝수/홀수 성질을 맞추는 검사 비트 | 안전 씰 및 체크리스트 |
| 신드롬 | 수신 측에서 패리티 검사를 통해 산출한 결과 값 (오류 위치 지시) | 위치 추적기 좌표 |
> 요약: 해밍 코드는 데이터 비트 사이에 교차 검증용 패리티 비트를 심어 신드롬으로 오류 위치를 찾음

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 패리티 삽입 | -> | 2. 패리티 계산 | -> | 3. 데이터 수신 | -> | 4. 신드롬 계산 |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 패리티 삽입: 송신할 데이터의 1, 2, 4, 8... 번째 위치에 패리티 비트 자리를 확보함
2. 패리티 계산: 짝수(또는 홀수) 패리티 규칙을 적용하여 각 패리티 비트가 담당하는 데이터 비트들의 값을 설정함
3. 데이터 수신: 전송 채널을 통해 데이터와 패리티 비트가 포함된 코드워드를 수신함
4. 신드롬 계산: 수신된 비트열로 다시 패리티를 검사하여 에러 위치(신드롬)를 찾아내고 해당 비트를 반전시켜 정정함
> 요약: 송신 전 중복 패리티를 계산하여 끼워 넣고, 수신 후 이를 재검사하여 단일 비트 오류를 정정함

## Ⅳ. 문제점
- 이중 비트 오류 무방비: 기본 해밍 코드는 1비트 오류만 정정 가능하며, 2비트 오류 발생 시 엉뚱한 비트를 수정하는 치명적 한계가 있음
- 오버헤드 발생: 데이터가 커질수록 패리티 비트의 추가 비율은 줄어들지만, 대역폭을 소모하는 통신 오버헤드가 생김

## Ⅴ. 개선방안
- 확장 해밍 코드(SEC-DED): 전체 비트에 대한 추가 패리티 비트 1개를 맨 앞에 덧붙여, 단일 비트 정정 및 이중 비트 오류 검출을 지원함
- CRC 및 고급 코딩 도입: 대용량 데이터 전송 시에는 오버헤드가 적은 CRC로 오류를 검출하고, 리드-솔로몬 등 강력한 정정 코드를 병행 사용함

## Ⅵ. 전망
- 해밍 코드는 메모리(ECC RAM) 등 근거리 고속 환경에서 주로 쓰이며, 원거리 통신에서는 LDPC나 폴라 코드 등 고효율 오류 제어 기술로 대체되는 추세임
