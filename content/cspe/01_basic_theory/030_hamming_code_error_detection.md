# 📖 【암기용】 개념 완전 이해

> 목적: 해밍 코드와 오류 검출·정정을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **해밍 거리(Hamming Distance)**는 두 비트열이 서로 몇 개의 자리에서 다른가를 세는 척도이며, 이 값이 한 부호(코드)가 **몇 비트의 오류까지 검출·정정할 수 있는지를 수학적으로 결정**한다. 해밍 코드(030_hamming_code.md 참고)는 이 원리를 실제 부호로 구현한 대표 사례다.
- **왜 필요한가**: "이 부호는 1비트 오류를 정정할 수 있다"는 말을 감이 아니라 숫자로 증명하려면, 부호가 만들어낼 수 있는 모든 코드워드 쌍 사이의 최소 거리를 알아야 한다. 이 최소 거리가 검출·정정 능력의 상한을 결정하기 때문에, 오류 제어 방식을 설계·비교할 때 반드시 해밍 거리부터 계산한다.
- **핵심 직관**: 코드워드들을 다차원 공간의 점이라고 생각하면, 해밍 거리는 두 점 사이의 "격자 거리"다. 점들이 서로 멀리 떨어져 있을수록(최소 거리가 클수록) 오류로 점이 조금 움직여도 원래 어느 점이었는지 헷갈리지 않고 구별·복원할 여유가 커진다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 해밍 거리(Hamming Distance) | 두 동일 길이 비트열이 다른 자릿수의 개수 — 이 문서의 상위 핵심 키워드 | 두 단어를 겹쳐놓고 다른 글자 칸을 세는 것 |
| 최소 해밍 거리(d_min) | 부호가 만들 수 있는 모든 코드워드 쌍 중 가장 가까운(작은) 거리 | 여러 등대 중 가장 가까운 두 등대 사이 거리 |
| 오류 검출(Detection) | 오류가 있다는 사실만 아는 것, 위치·정정은 불가 | 화재경보기 — 불났다는 것만 알려줌 |
| 오류 정정(Correction) | 오류의 위치까지 찾아 스스로 고치는 것 | 자동 소화기 — 위치까지 찾아 직접 끔 |
| 단순 패리티(Simple Parity) | 비트 1개로 홀수 개 오류만 검출(d_min=2) | 인원 점호에서 "짝수/홀수"만 확인 |
| SECDED | Single Error Correction, Double Error Detection — 1비트 정정+2비트 검출(d_min=4) | 1명 실종은 데려오고, 2명 실종은 경보만 울림 |
| CRC(순환 중복 검사) | 다항식 나눗셈 기반의 오류 검출 부호, 연집 오류에 강함 | 긴 문장을 통째로 나눗셈해 나머지만 대조 |
| 연집 오류(Burst Error) | 인접한 여러 비트가 한꺼번에 틀리는 오류 | 폭탄 한 방에 이웃 건물들이 동시에 무너짐 |

## 깊이 이해

### 해밍 거리와 정정 능력의 관계 — 왜 d_min ≥ 2t+1인가
- t개의 오류를 정정하려면, 원래 코드워드를 중심으로 반지름 t 이내에 있는 모든 오염된 비트열이 다른 어떤 코드워드의 반지름 t 영역과도 겹치지 않아야 한다. 두 코드워드 중심에서 각각 t씩 뻗어나간 영역이 안 겹치려면 두 중심 사이 거리가 최소 2t+1은 되어야 한다(t+t+1, 겹치지 않을 최소 간격).
- Hamming(7,4)의 최소 해밍 거리는 d_min=3이다. 2t+1=3을 풀면 t=1 — 정확히 1비트까지만 정정을 보장한다. 만약 2비트가 동시에 틀리면, 오염된 비트열이 원래 코드워드에서 거리 2만큼 떨어지는데, 이 지점이 다른 코드워드의 거리 1 영역 안에 들어갈 수 있어 "가장 가까운 코드워드"를 엉뚱한 곳으로 오판(오정정, Miscorrection)한다.

### 워크드 예제 — 다른 데이터로 신드롬 계산해 정정 능력의 경계를 검산
- 데이터 d1d2d3d4 = 1,1,0,1 을 위치 3,5,6,7에 채운다(위치3=d1=1, 위치5=d2=1, 위치6=d3=0, 위치7=d4=1).
- p1(위치1,3,5,7)=d1⊕d2⊕d4=1⊕1⊕1=1. p2(위치2,3,6,7)=d1⊕d3⊕d4=1⊕0⊕1=0. p4(위치4,5,6,7)=d2⊕d3⊕d4=1⊕0⊕1=0.
- 코드워드(위치1~7) = p1,p2,d1,p4,d2,d3,d4 = **1,0,1,0,1,0,1**.
- 이번엔 위치7(d4)에 오류를 주입해 1→0으로 뒤집혔다고 하자. 수신 = 1,0,1,0,1,0,**0**.
- 재검사: c1(위치1,3,5,7)=1⊕1⊕1⊕0=1. c2(위치2,3,6,7)=0⊕1⊕0⊕0=1. c4(위치4,5,6,7)=0⊕1⊕0⊕0=1.
- 신드롬=(c4,c2,c1)=(1,1,1)=111₂=**7** → 정확히 위치7을 가리켜 1비트 정정 성공.
- 이제 이 코드워드에서 **2비트**(예: 위치7과 위치6)가 동시에 틀렸다고 가정하면, 신드롬은 c1=1⊕1⊕1⊕0=1, c2=0⊕1⊕1⊕0=0(위치6도 0→1로 반전됨), c4=0⊕1⊕1⊕0=0 → 신드롬=(0,0,1)=001=1, 즉 위치1(사실은 멀쩡한 p1)을 오류로 지목해버려 엉뚱한 비트를 고치는 오정정이 발생한다. 이것이 d_min=3인 부호가 2비트 오류 앞에서 무너지는 실제 계산이다.

### 단순 패리티 vs 해밍 코드 vs SECDED vs CRC — 어떻게 갈라 쓰는가
- **단순 패리티(d_min=2)**: 비트 1개 추가로 홀수 개 오류(1개, 3개...)는 걸러내지만 짝수 개 오류(2개, 4개...)는 XOR 합이 우연히 다시 짝수가 되어 통과시켜버린다. 위치 정보가 전혀 없어 "정정"은 원천적으로 불가능하다 — 검출까지만 하는 가장 값싼 방식이다.
- **해밍 코드(d_min=3)**: 앞서 봤듯 1비트는 정확히 정정하지만 2비트 오류는 오정정 위험이 있다. 저비용 제어 신호처럼 오류율이 낮고 대부분 1비트 오류만 발생하는 환경에 적합하다.
- **SECDED, 즉 Hamming(8,4)(d_min=4)**: 기본 Hamming(7,4)에 코드워드 전체를 감시하는 전체 패리티 비트 1개를 추가한 것이다. d_min이 4로 늘어나면 2t+1=4에서 t는 1.5인데 정수가 아니므로, "1비트는 정정하되 2비트는 정정을 포기하고 검출만 한다"는 비대칭 전략을 쓴다 — 이것이 SECDED(Single Error Correction, Double Error Detection)다. 2비트 오류가 나면 전체 패리티가 불일치를 알아채 "정정하지 말고 에러로 처리하라"는 신호를 보내, 조용히 틀린 비트를 심는 대참사(Silent Data Corruption)를 막는다. 서버 ECC 메모리가 표준으로 이 방식을 쓰는 이유다.
- **CRC(순환 중복 검사)**: 해밍 계열과 근본적으로 접근이 다르다. 코드워드를 다항식으로 보고 특정 생성 다항식으로 나눈 나머지를 검사값으로 붙이는 방식이라, 인접한 여러 비트가 한꺼번에 틀리는 연집 오류(Burst Error)를 매우 높은 확률로 검출한다. 다만 CRC는 오류의 "위치"를 알려주지 않으므로 정정 기능이 없고, 오류를 발견하면 재전송(ARQ)을 요청해야 한다. 이더넷·TCP/IP·디스크 섹터처럼 즉시 재전송이 가능한 통신 환경에서 널리 쓰인다.
- **판별 원리**: 재전송이 가능한가(가능하면 CRC+ARQ로 대역폭 절약), 오류가 랜덤 단일 비트인가 연집인가(랜덤이면 해밍/SECDED, 연집이면 CRC나 리드-솔로몬), 오정정이 치명적인가(치명적이면 SECDED로 안전판 확보)의 세 가지 질문으로 정리된다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 해밍 코드는 패리티 비트를 2의 거듭제곱 위치에 배치해 syndrome으로 오류 위치를 찾는 선형 블록 코드이다.
> 2. **가치**: Hamming(7,4)는 4비트 데이터에 3비트 패리티를 추가해 1비트 오류를 검출·정정한다.
> 3. **판단 포인트**: 단순 패리티, 해밍, SECDED, CRC는 오류 위치 식별과 정정 가능 범위가 다르다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 오류 정정 원리 이해 확인 | 패리티 비트 2^i 위치 배치, syndrome으로 오류 위치 계산 | 검출(detection)과 정정(correction) 혼동 |
| 정정 능력 판단 확인 | 해밍 거리 3 = 1비트 정정, SECDED(거리 4) = 1정정+2검출 | 2비트 오류도 정정 가능하다는 과장 |
| 적용처 매핑 역량 확인 | ECC 메모리(SECDED), 전송 오류는 CRC+재전송 병행 | 계산 예시(Hamming 7,4) 없이 서술만 |

> 요약: 이 문제는 코드 이름 암기가 아니라 해밍 거리와 정정 한계, ECC 메모리 적용 판단을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 해밍 코드는 1비트 오류 정정을 위한 ECC 기법임
- 배경: 메모리와 통신 채널의 비트 오류는 프로그램 오동작과 데이터 손상을 유발함
- 필요성: 해밍 코드는 패리티 검사 결과인 syndrome으로 오류 위치를 산출해 재전송 없이 1비트 오류를 복구함


## Ⅱ. 구조 및 구성요소

```text
데이터비트 -> 패리티 삽입 -> 코드워드
패리티 위치 1,2,4 -> syndrome 계산 -> 오류 위치
수신 코드워드 -> syndrome 비0 -> 해당 비트 반전
```

| 구성요소 | 역할 | 수치 기준 |
|:---|:---|:---|
| 데이터 비트(k) | 실제 전송·저장 정보 | Hamming(7,4)의 k=4 |
| 패리티 비트(r) | 검사 집합별 짝/홀수 패리티 저장 | `2^r >= k+r+1` |
| 코드워드(n) | 데이터+패리티 전체 비트열 | n=k+r, 예: 7비트 |
| Syndrome | 패리티 재계산 결과 | 0=오류 없음, 비0=오류 위치 |

> 요약: 해밍 코드는 데이터, 패리티, 코드워드, syndrome의 조합으로 1비트 오류 위치를 산출한다.


## Ⅲ. 동작원리 및 흐름도

```text
데이터 입력 -> 패리티 위치 확보 -> 패리티 계산 -> 코드워드 전송/저장
-> 수신 후 재계산 -> syndrome 생성 -> 오류 비트 반전
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 패리티 비트 수 r 결정 | `2^r >= k+r+1` |
| 2 | 1,2,4,8 위치에 패리티 배치 | 2의 거듭제곱 위치 |
| 3 | 수신 코드워드에서 패리티 재계산 | 검사 집합별 XOR |
| 4 | syndrome 값으로 오류 위치 정정 | syndrome=5이면 5번 비트 반전 |

> 요약: 패리티 검사 결과를 이진 위치값으로 해석해 syndrome이 가리키는 비트를 반전하는 방식이다.


## Ⅳ. 특징

| 구분 | 단순 패리티 | 해밍 코드 | SECDED |
|:---|:---|:---|:---|
| 검출 범위 | 홀수 개 오류 검출 | 1비트 오류 검출 | 1비트 정정, 2비트 검출 |
| 정정 범위 | 정정 불가 | 1비트 정정 | 1비트 정정 |
| 추가 비트 | 1비트 | r비트, `2^r >= k+r+1` | r+1비트 |
| 적용 영역 | 저비용 링크 | 기본 ECC | 서버 DRAM ECC |

> 요약: 해밍 코드는 단순 패리티보다 오류 위치 식별이 가능하고, SECDED는 전체 패리티로 2비트 오류 검출 범위를 추가한다.


## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 오류 패턴 | 연집(Burst) 다중오류 | 랜덤 단일비트 오류 | 채널 오류 통계로 CRC/LDPC(연집)와 Hamming(랜덤) 중 분기 |
| 비용/성능 | CRC | Hamming ECC | 위치 식별·자동 정정이 필요할 때 |
| 운영/위험 | 재전송 의존 | FEC 기반 정정 | 메모리·저지연 링크에서 선택 |

> 요약: 해밍 코드는 단일 비트 정정이 필요한 메모리·제어 링크에 적합하고, burst 오류는 CRC/BCH/LDPC가 필요함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 2비트 오정정 | 기본 해밍 한계 | SECDED 전체 패리티 추가 | double error detect rate |
| burst 오류 | 연속 비트 손상 | CRC+BCH/LDPC 적용 | burst test 통과율 |
| 패리티 계산 오류 | 검사 집합 구현 누락 | syndrome truth table 검증 | syndrome coverage 100% |

> 요약: 해밍 코드 리스크는 다중 오류와 구현 누락이며 SECDED와 syndrome coverage로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 정정 능력 | 1비트 오류 100% 정정 | fault injection |
| 검출 능력 | 2비트 오류 100% 검출(SECDED) | ECC 테스트 |
| 오버헤드 | 64bit 데이터+8bit ECC | 메모리 구성 검토 |

> 요약: ECC 도입 효과는 1비트 정정률, 2비트 검출률, 비트 오버헤드로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ECC 메모리: 64비트 데이터에 8비트 ECC를 붙인 SECDED 구성으로 1비트 오류 자동 정정
2. 저장장치 검증: NAND Flash는 BCH/LDPC, 저비용 제어 메모리는 Hamming 계열 선택
3. 통신 프로토콜: 오류 정정은 FEC, 블록 무결성 검출은 CRC-32를 병행 적용

**결론 (2줄):**
- 기술사 판단: 단일 비트 soft error가 주 위험이면 SECDED, burst error가 주 위험이면 CRC+BCH/LDPC를 선택함
- 향후 방향: 고집적 메모리는 rowhammer·방사선 soft error 대응을 위해 ECC scrubbing과 patrol read를 병행함
