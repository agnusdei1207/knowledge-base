## Ⅰ. 개요

- **정의**: 해밍 코드(Hamming Code)는 데이터 비트 사이 특정 위치에 패리티 비트를 배치해 1비트 오류를 검출·정정하는 오류정정부호(ECC)임.
- **배경/필요성**: 패리티 비트 1개는 오류 발생 여부만 알려줄 뿐 오류 위치를 특정하지 못하므로, 여러 패리티 비트의 검사 결과를 조합해 오류 위치를 이진수로 직접 가리키는 방식이 필요함.
- **출제 의도**: 패리티 비트 위치 배치 규칙과 신드롬 디코딩 원리에 대한 이해, SECDED 확장 구조와 오버헤드 트레이드오프에 대한 적용 판단력을 확인함.
- **답안 방향**: 구조(패리티 비트 위치 규칙) → 동작(인코딩·신드롬 디코딩) → 특징(해밍 거리·오버헤드) → 비교(오류 제어 코딩 계열) → 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 패리티 비트 위치 배치와 오류 위치 판정 원리 설명 요구 | 2의 거듭제곱 위치 배치 규칙, 신드롬 계산식, 해밍 거리 $d=3$의 의미 | 패리티 위치 규칙 누락, 정정·검출 능력 혼동, 구체 비트 예시 없이 개념만 나열 |

> 요약: 해밍 코드 답안은 패리티 비트 위치 규칙과 신드롬 디코딩을 구체 비트열로 증명한 뒤, SECDED 확장의 필요성을 오버헤드·리스크 관점에서 판단해야 함.

## Ⅱ. 구조 및 구성요소

```text
코드워드 위치:  1    2    3    4    5    6    7
비트 종류:     P1   P2   D1   P4   D2   D3   D4

P1 담당 위치(위치의 이진 표현에서 1의 자리 비트=1): 1, 3, 5, 7
P2 담당 위치(위치의 이진 표현에서 2의 자리 비트=1): 2, 3, 6, 7
P4 담당 위치(위치의 이진 표현에서 4의 자리 비트=1): 4, 5, 6, 7
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 데이터 비트(D1~D4) | 실제 전송·저장 대상 정보 | 원본 답 |
| 패리티 비트(P1,P2,P4) | 담당 위치 그룹의 XOR 값을 저장 | 답안의 검산 표시 |
| 해밍 거리($d$) | 코드워드 간 최소 비트 차이. $d \geq 2t+1$이면 $t$비트 오류 정정 가능 | 오류 판별 여유폭 |
| 신드롬(Syndrome) | 수신 측이 재계산한 패리티 검사 결과의 이진 조합. 오류 위치를 직접 지시 | 진단 결과 |
| SECDED 전체 패리티 | 코드워드 전체에 대한 패리티 비트 1개 추가 | 2차 확인 장치 |

> 요약: 패리티 비트는 담당 위치 그룹의 XOR로 계산되고, 수신 측 신드롬이 그 계산을 재현해 오류 위치를 특정함.

## Ⅲ. 동작원리 및 흐름도

```text
데이터 비트 배치 -> 패리티 비트 계산(XOR) -> 코드워드 전송/저장
  -> 수신측 패리티 재검사 -> 신드롬 조합(이진수)
  -> 신드롬=0: 오류 없음 / 신드롬≠0: 해당 위치 비트 반전(정정)
```

- 1단계(비트 배치): 4비트 데이터 D1=1, D2=0, D3=1, D4=1을 2의 거듭제곱이 아닌 위치(3,5,6,7)에 놓고, 1·2·4번 위치는 패리티 비트로 비워둠.
- 2단계(패리티 계산): P1=D1⊕D2⊕D4=1⊕0⊕1=0, P2=D1⊕D3⊕D4=1⊕1⊕1=1, P4=D2⊕D3⊕D4=0⊕1⊕1=0으로 계산해 코드워드 `0110011`(순서대로 P1P2D1P4D2D3D4)을 생성함.
- 3단계(신드롬 계산): 6번 위치(D3)에 오류가 발생해 수신값이 `0110001`로 바뀌었다고 가정하면, S1=위치1⊕3⊕5⊕7=0, S2=위치2⊕3⊕6⊕7=1, S4=위치4⊕5⊕6⊕7=1이 되어 신드롬(S4S2S1)=110₂=6으로 오류 위치를 직접 지시함.
- 4단계(정정): 6번 비트를 반전해 원래 코드워드 `0110011`을 복원함. 신드롬이 0이면 오류 없음으로 판정함.

> 요약: 패리티 담당 위치의 XOR을 인코딩·디코딩 양쪽에서 동일하게 계산하며, 그 차이(신드롬)가 오류 위치를 이진수로 직접 알려줌.

## Ⅳ. 특징

- 해밍 거리 한계: 표준 해밍 코드는 $d=3$으로, 1비트 정정 또는 2비트 검출 중 하나만 보장하며 둘을 동시에 만족하지 않음.
- 오정정 위험: 2비트가 동시에 오류나면 신드롬이 실제로는 존재하지 않는 다른 1비트 오류로 해석되어 정정을 시도하므로, 오히려 데이터를 훼손하는 오정정(miscorrection)이 발생함.
- 오버헤드 감소 경향: 패리티 비트 수 $r$은 $2^r \geq m+r+1$을 만족해야 하며, 데이터 비트 $m$이 커질수록 상대 오버헤드($r/m$)가 감소함. 예: (7,4) 코드는 패리티 3비트로 오버헤드 43%(3/7)이나, (72,64) SECDED는 8/64=12.5%로 낮아짐.
- 버스트 오류 취약: 산발적 1비트 오류에는 강하나, 연속된 다중 비트가 동시에 손상되는 버스트 오류에는 대응하지 못함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 기준 | 패리티 비트 | 해밍 코드(SEC) | SECDED | BCH/LDPC |
|:---|:---|:---|:---|:---|
| 오류 검출 능력 | 1비트 | 2비트 | 2비트 | 다중 비트 |
| 오류 정정 능력 | 없음 | 1비트 | 1비트 | 다중 비트 |
| 오버헤드 특성 | 1비트 고정 | $r/m$, $m$ 증가 시 비율 감소 | 해밍 코드+1비트 | 가변, 정정 능력에 비례해 증가 |
| 대표 용도 | UART 등 단순 통신 | 저비용 저장 장치 | 서버 ECC RAM(DDR4/5) | SSD NAND, 5G/WiFi |

> 요약: 오류 특성(단일 vs 다중, 랜덤 vs 버스트)과 허용 오버헤드에 따라 패리티→해밍→SECDED→BCH/LDPC 순으로 정정 능력과 오버헤드가 함께 커짐.

**리스크·대응 (불릿):**
- 2비트 동시 오류 발생 시 순수 해밍 코드의 오정정 위험 → 코드워드 전체에 패리티 비트 1개(SECDED)를 추가해 2비트 오류는 정정하지 않고 검출만 하도록 설계함(지표: uncorrectable error 카운트).
- 버스트 오류가 잦은 매체(NAND 플래시)에 해밍 코드만 적용 시 정정 실패 → BCH/LDPC 등 다중 비트 정정 코드로 전환함(지표: 페이지당 정정 비트 수 대비 실제 오류 비트 수).

**도입 후 점검 지표 (불릿):**
- 정정·미정정 비율: ECC 컨트롤러 로그의 correctable/uncorrectable error 카운트를 주기적으로 확인함.
- 오버헤드 대비 효과: $r/m$ 비율과 실제 확보한 가용률(다운타임 감소분)을 함께 확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 메모리·저장 매체의 오류 특성(랜덤 단일비트 vs 버스트 다중비트)을 진단해 필요한 ECC 계열을 선정함.
2. 중기: 서버 메모리는 SECDED(72,64) ECC DIMM으로 표준화하고, NAND 기반 저장 장치는 BCH/LDPC 컨트롤러를 적용함.
3. 장기: ECC 로그 기반 정정·미정정 추이를 관측해 하드웨어 교체 및 용량 증설 기준에 반영함.

- 기술사적 판단: 오류가 산발적 1비트 위주면 해밍 코드 계열(SEC/SECDED)로 충분하나, 오류율이 높거나 버스트성이면 BCH/LDPC로 전환해야 함.
- 기술사 제언: SECDED 도입 시 2비트 오류를 "정정 대상"이 아닌 "검출 후 알림 대상"으로 설계 의도를 명확히 하여, 오정정으로 인한 조용한 데이터 훼손(silent corruption)을 방지함.
