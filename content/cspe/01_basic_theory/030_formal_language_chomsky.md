## Ⅰ. 개요
- **정의**: 문법 규칙의 제약 수준에 따라 형식 언어를 4단계로 분류한 계층 체계
- **배경/필요성**: 언어의 복잡도에 따라 인식 가능한 오토마타가 달라지므로, 문법-오토마타 대응 관계를 체계화할 필요가 있음
- **비유**: 건물 층수에 따라 필요한 구조물(기초·골조·엘리베이터)이 달라지는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 문법 유형과 오토마타 대응 관계 이해 | Type 0~3 각 문법의 생성 규칙 제약과 대응 오토마타 | Type 2(CFG)와 Type 3(정규)의 경계 조건 혼동 주의 |

> 요약: 문법 제약 수준에 따라 형식 언어를 4계층으로 분류하고 대응 오토마타를 매핑하는 체계임

## Ⅱ. 구성요소
```text
  +-----------------------------------------------+
  | Type 0: Unrestricted Grammar (Turing Machine)  |
  |  +------------------------------------------+  |
  |  | Type 1: Context-Sensitive (LBA)           |  |
  |  |  +-------------------------------------+  |  |
  |  |  | Type 2: Context-Free (PDA)           |  |  |
  |  |  |  +--------------------------------+  |  |  |
  |  |  |  | Type 3: Regular (FA)            |  |  |  |
  |  |  |  +--------------------------------+  |  |  |
  |  |  +-------------------------------------+  |  |
  |  +------------------------------------------+  |
  +-----------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Type 3 (정규 문법) | 생성 규칙이 `A -> aB` 또는 `A -> a` 형태로 제한되며, 유한 오토마타(FA)가 인식함 | 일직선 컨베이어 벨트로 처리 가능한 단순 작업 |
| Type 2 (문맥 자유 문법) | 생성 규칙이 `A -> alpha` 형태이며, 푸시다운 오토마타(PDA)가 인식함 | 스택 하나를 추가하면 처리 가능한 중첩 구조 작업 |
| Type 1 (문맥 의존 문법) | 생성 규칙이 `alpha A beta -> alpha gamma beta` 형태이며, 선형 유계 오토마타(LBA)가 인식함 | 주변 맥락을 봐야 판단 가능한 복잡 작업 |
| Type 0 (무제약 문법) | 생성 규칙에 제약이 없으며, 튜링 머신이 인식함 | 모든 종류의 작업을 수행할 수 있는 범용 기계 |

> 요약: Type 3(FA) ⊂ Type 2(PDA) ⊂ Type 1(LBA) ⊂ Type 0(TM) 포함 관계를 형성함

## Ⅲ. 절차
```text
  언어정의           문법유형판별       오토마타대응       인식/생성
  (알파벳+규칙)     (생성규칙분석)    (FA/PDA/LBA/TM)   (문자열판정)
       |              |              |              |
       +---명세------->+---분류------->+---매핑------->+
    형식언어 L       촘스키 계층      대응 오토마타    수락/거부 판정
```
- 1단계: 알파벳 집합과 생성 규칙으로 형식 언어 L을 정의함
- 2단계: 생성 규칙의 좌변·우변 형태를 분석하여 촘스키 계층(Type 0~3)을 판별함
- 3단계: 판별된 문법 유형에 대응하는 오토마타(FA, PDA, LBA, TM)를 매핑함
- 4단계: 대응 오토마타로 입력 문자열의 언어 소속 여부를 판정(수락/거부)함

> 요약: 언어 정의 → 문법 유형 판별 → 오토마타 매핑 → 문자열 판정 순서로 진행함

## Ⅳ. 문제점
- 계층 경계 판별 난이도: 주어진 언어가 Type 2인지 Type 1인지 판별하는 것 자체가 결정 불가능한 경우 존재함
- Type 0 결정 불가능성: 무제약 문법의 멤버십 문제는 튜링 머신의 정지 문제와 동치이므로 일반적 판정이 불가함
- 실용 적용 격차: Type 1(문맥 의존) 문법은 파싱 복잡도가 지수적이어서 실제 컴파일러에서 활용이 제한됨

> 요약: 계층 판별 난이도·결정 불가능성·실용 적용 격차가 주요 한계임

## Ⅴ. 개선방안
1. 단기: Pumping Lemma 등 형식적 증명 도구를 활용하여 Type 2/3 경계를 명확히 판별함
2. 중기: 결정 불가능 영역은 준결정적(Semi-decidable) 접근으로 범위를 한정하여 실용적 판정을 수행함
3. 장기: Mildly Context-Sensitive Grammar(TAG, CCG) 등 Type 1과 Type 2 사이의 실용적 문법 클래스를 활용함

> 요약: Pumping Lemma·준결정적 접근·중간 문법 클래스로 형식 언어 이론의 실용성을 확보함

## Ⅵ. 전망
- 발전 방향: 자연어 처리 분야에서 Mildly Context-Sensitive 문법이 인간 언어 모델링에 활용되는 추세임
- 기술사적 판단: 촘스키 계층은 계산 이론의 근간으로, 컴파일러·오토마타·계산 복잡도 문제의 공통 프레임워크임
- 기술사 제언: 문법 유형별 생성 규칙 제약과 대응 오토마타의 계산 능력 차이를 대비하여 이해해야 함
