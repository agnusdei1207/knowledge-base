# 📖 【암기용】 개념 완전 이해

> 목적: 암호 수학을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 암호 수학은 계산은 쉽지만 역계산은 어려운 수학 문제를 보안의 근거로 쓰는 체계임
- **왜 필요한가**: 인터넷 인증·전자서명·키 교환은 공개 채널에서 비밀을 지켜야 한다. RSA는 큰 수의 소인수분해, Diffie-Hellman은 이산 대수의 계산 난이도에 기반함.
- **핵심 직관**: 곱셈은 초등학생도 할 수 있지만, 2048비트 합성수를 원래 소수 2개로 되돌리는 일은 현행 범용 컴퓨터로 현실 시간 안에 처리하기 어렵다는 비대칭성을 이용함.

## 깊이 이해
- **배경·문제의식**: 대칭키 암호는 송신자와 수신자가 같은 키를 미리 공유해야 한다. 공개키 암호는 공개키를 배포하고 개인키를 숨겨 키 배송 문제를 줄임.
- **작동 원리**: RSA는 소수 p, q를 선택해 n=pq를 만들고, 오일러 피 함수 기반으로 공개 지수 e와 개인 지수 d를 구성함. 메시지는 `c = m^e mod n`, 복호는 `m = c^d mod n`으로 처리함.
- **비유**: 자물쇠는 누구나 잠글 수 있게 공개하고, 열쇠는 소유자만 가진 우편함 구조와 같다.
- **구체 예시**: TLS 1.3은 ECDHE로 세션키를 합의하고, 서버 인증서는 RSA-2048 또는 ECDSA P-256 서명으로 소유자를 증명함.
- **흔한 오해·주의점**: RSA는 원문을 그대로 거듭제곱하지 않는다. PKCS#1 OAEP 패딩, PSS 서명 패딩, 난수 품질이 없으면 동일 평문·선택 암호문 공격에 노출됨.

## 연결 개념
- 모듈러 연산 — 큰 정수 연산을 유한한 나머지 집합 안에서 처리하는 기반
- 공개키 기반구조(PKI) — 인증서·CA·서명 검증의 운영 체계
- 양자 알고리즘 — 쇼어 알고리즘은 RSA·ECC의 수학적 난제를 약화시키는 전환 압력

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 암호 수학은 소인수분해·이산 대수·타원곡선 이산 대수처럼 정방향 계산과 역방향 계산의 비용 차이를 보안 근거로 삼는 체계임.
> 2. **가치**: 공개키 암호는 키 사전 공유 없이 인증·전자서명·키 교환을 제공해 TLS, 전자문서, 블록체인의 신뢰 기반을 형성함.
> 3. **판단 포인트**: RSA-2048, ECC P-256, SHA-256, CSPRNG, 패딩 표준 적용 여부가 수학적 안전성과 구현 안전성을 함께 결정함.

---

## Ⅰ. 개요 및 필요성

- 개요: 계산은 쉽지만 역계산은 어려운 수학 문제로 기밀성·무결성·인증을 보장하는 기반 이론
- 배경: 공개 네트워크에서는 키 배송, 서명 검증, 신원 확인이 필요하며 RSA는 소인수분해, Diffie-Hellman은 이산 대수 난제로 이를 환원함
- 필요성: 기술사 답안은 수학 난제, 알고리즘 구조, 구현 리스크를 함께 제시해야 함

---

## Ⅱ. 구조 및 구성요소

```text
난수 생성 -> 소수/군 선택 -> 키 생성 -> 암호/서명 연산 -> 검증
             / RSA: 소인수분해
             / DH: 이산 대수
             / ECC: 타원곡선 이산 대수
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 수학 난제 | 역계산 비용의 근거 제공 | RSA 소인수분해, DH 이산 대수, ECC ECDLP |
| 키 생성 | 공개키·개인키 쌍 구성 | RSA-2048 이상, ECC P-256 이상 권고 |
| 암호 연산 | 암호화·서명·키 교환 수행 | OAEP, PSS, ECDHE 등 표준 모드 적용 |
| 검증 체계 | 인증서·해시·서명 검증 | X.509, SHA-256, CRL/OCSP 확인 |

> 요약: 암호 수학은 난제 선택 -> 키 생성 -> 연산 -> 검증 체계가 연결될 때 공개 채널에서 신뢰를 제공함.

---

## Ⅲ. 동작원리 및 흐름도

```text
파라미터 선택 -> 키쌍 생성 -> 공개키 배포 -> 암호/서명 수행 -> 개인키 연산 -> 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 소수, 군, 곡선, 난수 선택 | NIST SP 800-56, FIPS 186-5 준수 |
| 2 | 공개키·개인키 생성 | 키 길이 RSA-2048 이상, 개인키 접근통제 |
| 3 | 암호화·서명 수행 | OAEP/PSS, SHA-256 이상 해시 |
| 4 | 복호·검증 수행 | 인증서 체인, 만료일, 폐기 상태 확인 |

> 요약: 암호 연산은 표준 파라미터와 난수 품질을 전제로 키 생성, 공개키 연산, 개인키 연산, 검증 순서로 동작함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 공개키 배포로 사전 비밀 공유 부담 감소 | TLS 인증서, 전자서명, ECDHE 키 교환 |
| 한계 | 개인키 유출 시 서명 위조·복호 가능 | HSM, 키 회전 주기 1년 이하, 접근 감사 |
| 비교 대상 | 대칭키는 AES-128/256으로 대량 데이터 처리 | 공개키는 키 교환·서명, 대칭키는 본문 암호화 |
| 수치 기준 | RSA-2048은 최소 기준, ECC P-256은 짧은 키로 동등 보안 수준 제공 | 장기 보존 문서는 RSA-3072 또는 P-384 검토 |

> 요약: 공개키 암호는 키 배송과 인증에 쓰고, 대량 데이터는 AES-GCM 같은 대칭키로 분리하는 하이브리드 구조가 표준 선택임.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 대칭키 사전 공유 | 공개키·개인키 분리 | 불특정 다수 통신이면 공개키 기반 |
| 비용/성능 | AES-GCM은 본문 암호화 처리량 중심 | RSA/ECC는 키 교환·서명 중심 | 1MB 이상 데이터는 하이브리드 암호 |
| 운영/위험 | 비밀번호 기반 키 관리 | PKI, HSM, 인증서 수명 관리 | 감사 요구 있으면 X.509·OCSP 적용 |

> 요약: 공개키 암호는 신뢰 시작점과 키 교환에 배치하고, 데이터 본문은 대칭키로 처리하는 조건부 조합이 적합함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 약한 난수 | 예측 가능한 CSPRNG | OS CSPRNG, HSM 난수, FIPS 140-3 모듈 | 난수 자체진단 로그, 키 생성 실패율 |
| 패딩 오용 | Raw RSA, 동일 평문 반복 | OAEP 암호화, PSS 서명, 라이브러리 고정 | 정적 분석, 암호 API 사용 목록 |
| 양자 전환 | 쇼어 알고리즘의 RSA/ECC 영향 | PQC 하이브리드 KEM, crypto-agility 설계 | NIST PQC 지원률, 인증서 교체율 |

> 요약: 암호 수학의 실무 리스크는 수학보다 난수·패딩·키관리·양자 전환 계획에서 주로 발생함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 키 강도 | RSA-2048 이상, ECC P-256 이상 | 인증서 스캔, 키 인벤토리 |
| 구현 적합성 | SHA-256 이상, OAEP/PSS 적용 | SAST, 암호 라이브러리 정책 점검 |
| 운영 통제 | 개인키 HSM 보관, 키 회전 12개월 이하 | 감사로그, KMS 정책, OCSP 응답률 |

> 요약: 암호 도입 후에는 키 길이, 표준 모드, 개인키 보관, 회전 주기를 지표로 수학적 가정이 운영 통제로 이어지는지 점검함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 인증·서명: RSA-2048 이상 또는 ECDSA P-256 이상 인증서를 사용하고 SHA-256 해시와 OCSP 검증을 기본값으로 적용함.
2. 키 교환: TLS 1.3 ECDHE를 적용해 전방향 안전성(PFS)을 확보하고 세션키는 AES-128-GCM 또는 AES-256-GCM으로 분리함.
3. 키 관리: 개인키는 HSM/KMS에 저장하고 키 회전 12개월 이하, 접근 로그 1년 이상 보관, 관리자 MFA 적용을 점검함.

**결론 (2줄):**
- 기술사 판단: 인터넷 공개 통신이면 PKI+ECDHE+AES-GCM 조합, 장기 보존·규제 문서면 RSA-3072/P-384와 HSM 적용이 타당함.
- 향후 방향: RSA/ECC 단독 구조에서 NIST PQC 기반 KEM과 기존 ECDHE를 병행하는 하이브리드 전환이 필요함.
