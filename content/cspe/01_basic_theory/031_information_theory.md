## 미리 알고가기

- 정보량: 드문 사건일수록 더 많은 정보를 준다는 관점에서 확률의 로그로 측정하는 값임
- 엔트로피: 확률 변수의 평균 정보량이며 불확실성의 크기를 비트 단위로 나타냄
- 상호 정보: 채널 출력을 보고 입력에 대해 얻는 정보량임
- 채널 용량: 주어진 채널에서 오류 없이 보낼 수 있는 최대 정보율임
- 섀넌 한계: 잡음 채널에서 신뢰 가능한 통신률의 이론적 상한임

## Ⅰ. 개요

- **정의**: 정보이론은 메시지의 불확실성을 엔트로피로 측정하고 채널의 전달 한계를 용량 기준으로 계산하는 수학 체계이며, 압축률과 통신 신뢰도의 이론적 한계를 판단하기 위해 사용함.
- **배경/필요성**: 데이터 압축은 중복을 얼마나 제거할 수 있는지, 통신 시스템은 잡음 속에서 얼마나 빠르게 보낼 수 있는지를 알아야 하므로 공통의 정량 기준이 필요함.
- **비유**: 짐의 최소 부피와 도로의 최대 통행량을 계산해 포장과 운송 계획을 동시에 세우는 기준과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엔트로피와 채널 용량 의미 설명 | H(X), I(X;Y), C, 잡음 | 공식 암기만 제시 |
| 압축·통신 한계 연결 | 소스 코딩 정리, 채널 코딩 정리 | 압축률과 오류정정 목적 혼동 |

> 요약: 정보이론은 데이터의 최소 표현 길이와 잡음 채널의 최대 신뢰 전송률을 정량화하는 기준임.

## Ⅱ. 특징/비교

| 판단 기준 | 소스 관점 | 채널 관점 |
|:---|:---|:---|
| 핵심 질문 | 메시지를 얼마나 짧게 표현할 수 있는가 | 잡음 속에서 얼마나 빠르게 믿고 보낼 수 있는가 |
| 핵심 지표 | 엔트로피 H(X), 평균 코드 길이 | 상호 정보 I(X;Y), 채널 용량 C |
| 설계 대상 | 압축, 부호 길이, 중복 제거 | 오류정정, 변조, 대역폭·SNR |
| 선택 기준 | 저장·전송 비트 수 절감이 중요할 때 | 오류율과 전송률 균형이 중요할 때 |

- **압축 기준**: 평균 코드 길이는 엔트로피보다 작아질 수 없으며, 엔트로피에 가까울수록 효율적임.
- **전송 기준**: 전송률이 채널 용량보다 낮으면 적절한 코딩으로 오류율을 낮출 수 있음.
- **분리 기준**: 이상적 조건에서는 소스 코딩과 채널 코딩을 분리해 설계할 수 있음.

> 요약: 정보이론은 압축에서는 엔트로피를, 통신에서는 채널 용량을 기준으로 설계 가능성과 한계를 판단함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Source     | ---> | Encoder    | ---> | Channel    |
| X          |      | Coding     |      | Noise      |
+------------+      +------------+      +------------+
       |                                      |
       v                                      v
+------------+      +------------+      +------------+
| Entropy    |      | Mutual     |      | Capacity   |
| H(X)       |      | Info I     |      | C          |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정보원 | 확률 분포를 갖는 메시지를 생성하는 대상임 | 짐을 만드는 공장 |
| 엔트로피 H(X) | 정보원의 평균 불확실성을 비트 단위로 측정함 | 짐의 최소 포장 부피 |
| 부호화 | 메시지를 비트열로 바꾸거나 오류에 견디도록 중복을 배치함 | 포장 방식 |
| 상호 정보 I(X;Y) | 출력 관찰로 입력에 대해 얻은 정보량을 나타냄 | 도착 후 확인 가능한 내용 |
| 채널 용량 C | 채널이 신뢰성 있게 전달할 수 있는 최대 정보율임 | 도로의 최대 처리량 |

> 요약: 정보이론은 정보원 확률, 부호화 방식, 잡음 채널을 엔트로피와 채널 용량으로 연결해 압축과 통신의 한계를 계산함.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Model      | ---> | Measure    | ---> | Select     | ---> | Verify     |
| Prob       |      | H and C    |      | Coding     |      | Rate/Error |
+------------+      +------------+      +------------+      +------------+
```

1. **확률 모델링**: 메시지 심볼의 발생 확률과 채널의 잡음 특성을 추정함.
2. **한계 계산**: 엔트로피, 상호 정보, 채널 용량을 계산해 압축률과 전송률 상한을 구함.
3. **코딩 선택**: 소스 코딩은 중복 제거, 채널 코딩은 오류 제어 목적에 맞게 선택함.
4. **성능 검증**: 평균 코드 길이, 전송률, BER/FER을 측정해 이론 한계와 실제 성능 차이를 확인함.

> 요약: 정보이론 적용은 확률 모델을 세우고 이론 한계를 계산한 뒤 코딩 방식을 선택해 실제 지표로 검증하는 과정임.

## Ⅴ. 문제점

- **P1 확률 모델 불일치**: 실제 데이터 분포가 가정과 다르면 엔트로피와 최적 코드 길이 판단이 틀어짐.
- **P2 한계와 구현 간 격차**: 섀넌 한계는 이론적 상한이므로 실제 코드의 복잡도와 지연은 별도 문제가 됨.
- **P3 지표 오해**: 엔트로피, 압축률, 전송률, 오류율을 같은 축으로 비교하면 설계 목적이 흐려짐.

> 요약: 정보이론은 확률 모델, 구현 비용, 지표 해석을 분리하지 않으면 이론값을 실무 성능으로 오해하기 쉬움.

## Ⅵ. 개선방안

- **P1 대응**: 실제 데이터 샘플로 분포를 추정하고 적응형 코딩 또는 주기적 모델 갱신을 적용함. (확인: 평균 코드 길이)
- **P2 대응**: LDPC, Turbo, Polar 코드처럼 한계에 가까운 코드를 지연·전력 제약과 함께 평가함. (확인: BER, latency, power)
- **P3 대응**: 압축은 bits/symbol, 통신은 bits/s/Hz와 BER처럼 목적별 지표를 분리해 제시함. (확인: 지표 정의표)

> 요약: 정보이론의 실무 적용은 데이터 기반 모델링과 목적별 지표 분리, 구현 제약 평가를 함께 수행해야 함.

## Ⅶ. 전망

- **발전 방향**: 5G/6G, 위성통신, 저장장치, 생성형 AI 압축에서 정보이론 기반 한계 분석은 계속 중요해질 전망임.
- **기술사적 판단**: 압축·통신·암호·AI 시스템은 모두 불확실성 정량화와 한계 판단이 필요하므로 정보이론 지표를 공통 언어로 써야 함.
- **기술사 제언**: 답안에서는 엔트로피와 채널 용량을 분리해 설명하고, 소스 코딩과 채널 코딩의 목적 차이로 마무리해야 함.
