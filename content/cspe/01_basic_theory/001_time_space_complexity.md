# 알고리즘 시간복잡도·공간복잡도 (Time/Space Complexity)

## 1. 정의 및 개념

| 구분 | 정의 | 분석 대상 |
|---|---|---|
| **시간복잡도(Time Complexity)** | 입력 크기 증가에 따라 알고리즘 수행 시간이 얼마나 증가하는지를 함수로 표현한 기준 | 비교, 대입, 산술, 탐색, 병합 등 기본 연산 횟수 |
| **공간복잡도(Space Complexity)** | 입력 저장 공간 외에 알고리즘 수행 중 추가로 필요한 메모리 증가량을 함수로 표현한 기준 | 보조 배열, 큐, 스택, 해시 테이블, 재귀 호출 스택 |
| **점근 분석(Asymptotic Analysis)** | 입력 크기가 충분히 커질 때 지배적인 증가율을 중심으로 비용을 비교하는 방식 | `O`, `Theta`, `Omega` 표기 |

복잡도 분석은 실행 시간을 초 단위로 맞히는 작업이 아니라, 데이터가 커질 때 알고리즘이 감당 가능한지 사전에 판단하는 설계 기준이다.

## 2. 분석 기준 및 절차

1. **입력 크기 정의**
   - 배열: 원소 수 `n`
   - 그래프: 정점 수 `V`, 간선 수 `E`
   - 행렬: 행·열 크기
   - 문자열: 길이 또는 문자 집합 크기

2. **기본 연산 산정**
   - 반복문 수행 횟수
   - 중첩 반복문의 반복 범위
   - 재귀 호출 수와 깊이
   - 자료구조 접근 비용

3. **공간 사용량 산정**
   - 입력 자체를 제외한 추가 공간인지 포함 공간인지 기준 명시
   - 임시 배열, DP 테이블, 해시 인덱스, 재귀 스택 포함

4. **점근 표기 변환**
   - 상수 계수와 하위항 제거
   - 큰 입력에서 지배적인 항을 기준으로 표기

5. **요구사항 적합성 판단**
   - 응답시간 목표, 메모리 한계, 데이터 증가 전망, 서비스 수준 협약(Service Level Agreement, SLA)과 연결

## 3. 대표 복잡도와 해석

| 복잡도 | 대표 예 | 기술사적 해석 |
|---|---|---|
| **O(1)** | 배열 인덱스 접근, 스택 push/pop | 입력 크기와 무관하지만 충돌·잠금·캐시 비용은 별도 검토 |
| **O(log n)** | 이진 탐색, 균형 트리 탐색 | 후보 공간이 매 단계 일정 비율로 감소 |
| **O(n)** | 선형 탐색, 전체 스캔 | 모든 원소 확인이 필요한 기본 비용 |
| **O(n log n)** | 병합 정렬, 힙 정렬, 평균 퀵 정렬 | 대규모 비교 정렬의 일반적 효율 구간 |
| **O(n²)** | 모든 쌍 비교, 단순 중첩 반복 | 입력 증가에 민감하여 규모 제한 또는 개선 필요 |
| **O(2ⁿ), O(n!)** | 완전탐색, 순열 탐색 | 실무 대규모 적용 곤란, DP·가지치기·근사 필요 |

## 4. 시간-공간 트레이드오프

| 시간 절감 방식 | 추가 공간 비용 | 적용 예 |
|---|---|---|
| 해시 테이블 사용 | 버킷, 충돌 처리 공간 | 중복 검사, 캐시 조회 |
| 메모이제이션 | 상태 저장 테이블 | 동적 프로그래밍(Dynamic Programming, DP) |
| 인덱스 구축 | 인덱스 저장 공간 | 데이터베이스 검색 |
| 캐시 저장 | 캐시 메모리와 무효화 비용 | 반복 질의 응답 |
| 제자리 처리 | 반복 계산 증가 가능 | 메모리 제한 환경 |

시간을 줄이기 위해 공간을 쓰거나, 공간을 줄이기 위해 계산을 반복하는 선택이 많으므로 두 지표는 항상 함께 판단해야 한다.

## 5. 심화 이슈 (기술사 포인트)

1. **실행시간과 복잡도 혼동**
   - `O(n)`이 항상 `O(log n)`보다 느린 것은 아니며, 작은 입력에서는 상수 계수·캐시 지역성이 더 클 수 있다.

2. **최악·평균·상각 조건 구분**
   - 해시 테이블 평균 `O(1)`, 퀵 정렬 평균 `O(n log n)`처럼 조건부 성능을 보장 성능처럼 쓰면 안 된다.

3. **입력 변수 누락**
   - 그래프 알고리즘은 `n` 하나보다 `V`, `E`로 표현해야 비용 구조가 명확하다.

4. **I/O·네트워크 병목**
   - 외부 정렬, 분산 처리, 대용량 로그 분석에서는 CPU 연산보다 디스크·네트워크 비용이 지배적일 수 있다.

5. **운영 검증**
   - 이론 복잡도와 함께 p95/p99 지연, 메모리 피크, 입력 분포별 벤치마크가 필요하다.

## 6. 결론

시간복잡도와 공간복잡도는 알고리즘을 선택할 때 가장 먼저 적용하는 확장성 판단 기준이다. 기술사 답안에서는 단순히 `O(n)` 표기를 나열하는 것이 아니라, 입력 규모·기본 연산·보조 공간·최악 조건·운영 제약을 연결해 알고리즘 선택 근거를 제시해야 한다.
