## 미리 알고가기

- 입력 크기 $n$: 알고리즘의 자원 사용량을 결정하는 데이터의 규모나 차원임
- 기본 연산: 전체 수행 시간을 좌우하는 핵심 작업 단위로, 비교·교환·대입 등이 있음
- 지배항: 입력이 커질 때 비용 함수의 증가율에 가장 큰 영향을 미치는 최고차항임
- 트레이드오프(Trade-off): 메모리를 더 써서 속도를 높이거나, 속도를 희생해 메모리를 아끼는 상충 관계임

## Ⅰ. 개요

- **정의/개념**: 알고리즘 복잡도는 입력 데이터 크기 $n$이 증가함에 따라 연산 횟수(시간)와 메모리 점유량(공간)이 변하는 추이를 수학적 함수로 표현해 알고리즘의 효율성을 판단하는 척도임
- **배경/필요성**: 동일한 기능을 수행하더라도 입력 규모가 커지면 지연 시간과 메모리 사용량이 급증할 수 있으므로, 구현 단계 이전부터 알고리즘의 확장 한계를 예측하고 통제할 기준이 필요함

## Ⅱ. 특징

- 특정 하드웨어의 성능이나 프로그래밍 언어의 처리 속도에 의존하지 않고 알고리즘 구조 자체의 효율성을 객관적으로 비교할 수 있음
- 상수항이나 하위 차수 항을 제거하는 점근적 분석을 통해 입력이 충분히 커질 때의 증가율을 식별함
- 시간과 공간 사이의 상충 관계를 분석하여 시스템의 가용 자원 조건에 맞는 알고리즘 선택 기준을 제공함

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| **분석 대상** | 입력 증가에 따른 기본 연산 수행 횟수 | 알고리즘 실행을 위해 추가로 필요한 메모리양 |
| **병목 지점** | 응답 지연($Latency$), 처리량($Throughput$) 저하 | 메모리 부족($OOM$), 스와핑 발생, 캐시 효율 저하 |
| **최적화 방향** | 반복문 축소, 메모이제이션 적용, 탐색 범위 제한 | 제자리 정렬($In-place$), 스트리밍 처리, 재사용 |

> 요약: 시간복잡도는 시스템의 실행 속도를 결정하고, 공간복잡도는 가용 메모리 한계 내 동작 여부를 결정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 ($n$) | 데이터의 개수나 행렬의 차원처럼 알고리즘 자원 소모량의 변수가 되는 기준값임 |
| 기본 연산 | 반복문 내부에서 가장 자주 수행되어 수행 시간을 지배하는 연산 단위임 |
| 비용 함수 $f(n)$ | 입력 $n$에 대한 실제 연산 횟수나 메모리 사용량을 수학적 식으로 도출한 결과임 |
| 점근 표기법 | 비용 함수에서 상수를 제거하고 최고차항만 남겨 증가율을 추상화한 표기 방식임 |

```text
[ 분석 구조 ]
+-----------+      +-----------+      +-----------+
| 입력 규모  | ---> | 연산/메모리 | ---> | 복잡도 도출 |
|   (n)     |      | 카운팅     |      |  (점근표기) |
+-----------+      +-----------+      +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 연산 단위 식별 | --> | 비용 함수 산출 | --> | 최고차항 추출 | --> | 점근 표기 확정 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **단위 식별** — 수행 시간을 결정하는 핵심 연산과 메모리를 점유하는 보조 자료구조를 정의함
2. **함수 산출** — 코드의 반복문 깊이와 재귀 호출 횟수를 분석하여 입력 $n$에 대한 수식을 작성함
3. **항 추출** — 수식에서 입력이 커질수록 영향력이 미미해지는 상수와 낮은 차수의 항을 제거함
4. **표기 확정** — $O(g(n))$과 같은 형식으로 분석 대상 상황의 자원 소모 증가율을 표기함

## Ⅵ. 실무 적용 및 유의점

1. 대규모 트래픽 처리 시스템에서는 평균 응답만 보면 특정 입력에서 지연과 메모리 사용량이 급증할 수 있으므로, 최악 입력 기준의 상한을 산정하고 p99 지연 시간과 최대 메모리 사용량으로 검증해야 함
2. 캐싱처럼 메모리를 더 써서 처리 속도를 높이는 구조에서는 보조 공간이 시스템 임계치를 넘지 않도록 데이터 수명($TTL$)과 교체 알고리즘($LRU$ 등)을 정하고 캐시 적중률과 메모리 사용량으로 확인해야 함

## Ⅶ. 결론

- 알고리즘 복잡도는 입력 규모가 커질 때 지연 시간과 메모리 사용량이 감당 가능한지 판단하는 설계 기준이므로, 시간과 공간의 트레이드오프를 업무 요구와 자원 한계에 맞춰 선택해야 함
