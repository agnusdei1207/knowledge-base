## 미리 알고가기

- 입력 크기 $n$: 데이터 개수나 행렬 차원처럼 비용 함수를 세는 기준값임
- 기본 연산: 비교·교환·대입처럼 알고리즘 지연을 좌우하는 반복 작업임
- 추가 메모리: 입력 자체를 제외하고 알고리즘이 더 확보하는 저장 공간임
- 지배항: 큰 입력에서 비용 증가율을 사실상 결정하는 최고차항임
- 트레이드오프: 시간을 줄이기 위해 메모리를 더 쓰거나 반대로 조정하는 상충 관계임

## 작성 근거(검토용)

- **개요 구성**: 입력 크기, 기본 연산, 추가 메모리를 함께 넣어 시간·공간 판단 대상을 분리함
- **특징 선정**: 구조 독립 비교, 비용 함수 원천, 지배항, 트레이드오프가 실제 알고리즘 선택을 바꿈
- **Ⅲ 비교축**: 시간은 지연과 처리량, 공간은 메모리 부족과 캐시 미스를 만들기 때문에 병목·개선 방향으로 정리함
- **구조 도식**: 입력 규모에서 비용 산출과 점근 표기로 이어지는 흐름이 분석 절차 자체라 포함함
- **실무 유의점**: 트래픽 상한과 캐싱은 복잡도 분석이 운영 지표로 검증되는 대표 조건이라 남김

## Ⅰ. 개요

- **정의/개념**: 알고리즘 시간·공간복잡도는 입력 크기 $n$ 증가에 따른 기본 연산 수와 추가 메모리 사용량을 함수로 표현해 확장 한계를 판단하는 기준임
- **배경/필요성**: 구현 전 병목과 자원 한계를 예측하기 위해 입력 크기별 시간·공간복잡도 분석이 필요함

## Ⅱ. 특징

- 하드웨어·언어 영향을 걷어내고 알고리즘 구조 자체의 증가율을 비교함
- 반복문 깊이·재귀 분기·자료구조 접근이 비용 함수를 결정함
- 지배항 중심 표기로 대규모 입력에서 깨지는 지점을 먼저 드러냄
- 시간과 공간의 트레이드오프에서 어떤 자원을 더 쓸지 선택하는 근거가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| **분석 대상** | 입력 증가에 따른 기본 연산 수행 횟수 | 알고리즘 실행에 추가로 필요한 메모리 양 |
| **병목** | 지연 증가, 처리량 저하 | 메모리 부족, 스와핑, 캐시 미스 |
| **개선 방향** | 반복 축소·메모이제이션·탐색 제한 | 제자리 처리·스트리밍·버퍼 재사용 |

> 요약: 시간은 응답 한계, 공간은 메모리 한계를 판단함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 $n$ | 비용 변화를 관찰하는 기준이며 문제마다 원소 수·정점 수·행렬 차원으로 잡음 |
| 기본 연산 | 비교·교환·대입처럼 가장 자주 반복되어 시간 비용을 대표하는 작업임 |
| 추가 메모리 | 보조 배열·스택·캐시처럼 입력 외에 확보하는 공간이며 공간복잡도의 대상임 |
| 비용 함수 $f(n)$ | 입력 크기별 연산 수와 메모리 사용량을 수식으로 나타낸 결과임 |
| 점근 표기 | 상수와 하위항을 제거해 증가율 판단에 필요한 지배항만 남긴 표기임 |

```text
[ 분석 구조 ]
+-----------+      +-----------+      +-----------+
| 입력 규모  | ---> | 연산·메모리 | ---> | 복잡도 도출 |
|   (n)     |      | 카운팅     |      |  (점근표기) |
+-----------+      +-----------+      +-----------+
```

> 요약: 입력 규모를 기준으로 비용을 세고 지배 증가율만 남김.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 연산 단위 식별 | --> | 비용 함수 산출 | --> | 최고차항 추출 | --> | 점근 표기 확정 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **단위 식별**: 시간 지배 연산과 입력 외 보조 메모리를 정함
2. **함수 산출**: 반복 깊이, 재귀 분기, 자료구조 접근을 $n$의 식으로 씀
3. **지배항 추출**: 큰 입력에서 영향이 작은 상수와 하위항을 제거함
4. **판단 연결**: $O(g(n))$ 표기를 지연·메모리 한계와 연결함

> 요약: 코드 구조를 비용 함수로 바꾼 뒤 지배항으로 표기함.

## Ⅵ. 실무 적용 및 유의점

1. 대규모 트래픽 경로는 최악 입력 상한으로 시간복잡도를 검토하고 p99 지연·처리량으로 검증함
2. 캐싱·메모이제이션은 시간을 줄이는 대신 공간을 쓰므로 TTL·LRU를 적용하고 적중률·최대 메모리로 확인함

## Ⅶ. 결론

- 알고리즘 복잡도는 입력 증가에 따른 지연·메모리 한계를 예측해 구현 전 선택을 검증하는 기준임
