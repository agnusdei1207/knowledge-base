## 핵심 답안

시간복잡도와 공간복잡도는 알고리즘이 입력 크기 증가에 따라 수행 연산과 추가 메모리를 얼마나 더 요구하는지를 함수로 표현해, 주어진 성능·비용·확장성 조건에서 어떤 알고리즘을 선택할지 판단하는 기준임.

기술사 답안에서는 `O(n)` 같은 표기 자체보다 **입력 규모를 무엇으로 둘 것인지**, **시간과 공간 중 어떤 자원이 병목인지**, **최악·평균·상각 조건 중 어떤 관점으로 보장할 것인지**를 함께 제시해야 함.

```text
입력 규모 정의 -> 기본 연산/보조공간 산정 -> 점근 표기 -> 요구사항 적합성 판단
        n,V,E              T(n), S(n)          O/Theta/Omega        SLA, 메모리, 비용
```

## 개념 정리

| 구분 | 의미 | 답안에서의 역할 |
|:---|:---|:---|
| 시간복잡도 `T(n)` | 입력 크기 `n`에 따라 기본 연산 횟수가 증가하는 정도 | 응답시간, 처리량, 배치 시간 한계 판단 |
| 공간복잡도 `S(n)` | 입력 저장 공간 외에 알고리즘 수행 중 필요한 추가 메모리 증가 정도 | 메모리 한계, 동시 처리량, 캐시 효율 판단 |
| 점근 표기 | 상수와 하위항을 제거하고 큰 입력의 지배적 증가율을 표현 | 알고리즘 간 구조적 확장성 비교 |
| 경우 분석 | 최선·평균·최악·상각 조건별 비용 구분 | 성능 보장 수준과 운영 리스크 설명 |

시간복잡도는 실제 초 단위 실행시간이 아니며, 공간복잡도도 전체 시스템 메모리 사용량 자체가 아니라 알고리즘 선택으로 추가되는 메모리 비용을 중심으로 분석함.

## 분석 방법

1. **입력 규모 선정**: 배열은 원소 수 `n`, 그래프는 정점 `V`와 간선 `E`, 행렬은 행·열 크기처럼 비용을 좌우하는 변수를 먼저 정의함
2. **기본 연산 산정**: 반복문, 중첩 반복문, 재귀 호출, 자료구조 접근에서 가장 지배적인 비교·대입·탐색·병합 횟수를 계산함
3. **보조 공간 산정**: 임시 배열, 큐·스택, 해시 테이블, 재귀 호출 스택, 캐시용 인덱스 등 입력 외 추가 공간을 계산함
4. **점근 표기 변환**: 비용 함수의 지배항을 기준으로 `O`, `Theta`, `Omega`를 구분하고, 최악·평균·상각 조건을 명시함
5. **설계 판단 연결**: 데이터 증가율, 응답시간 목표, 메모리 한계, 입출력 병목, 구현 복잡도를 기준으로 알고리즘 채택 여부를 결정함

예를 들어 정렬된 배열에서 단일 검색은 이진 탐색의 `O(log n)`이 유리하지만, 데이터가 자주 삽입·삭제되면 정렬 유지 비용까지 포함해 균형 트리나 해시 인덱스와 비교해야 함.

## 대표 복잡도 해석

| 복잡도 | 대표 사례 | 기술사적 해석 |
|:---|:---|:---|
| `O(1)` | 배열 인덱스 접근, 해시 평균 조회 | 조건이 맞을 때만 상수 시간이며 충돌·캐시·동시성 비용을 별도 확인해야 함 |
| `O(log n)` | 이진 탐색, 균형 트리 탐색 | 정렬성 또는 균형 유지 비용을 감수하고 검색 비용을 낮춘 구조임 |
| `O(n)` | 선형 탐색, 단순 스캔 | 전체 데이터 확인이 필요하거나 스트리밍 처리에 적합함 |
| `O(n log n)` | 병합 정렬, 힙 정렬, 평균 퀵 정렬 | 비교 기반 정렬의 일반적 효율 구간이며 안정성·메모리 조건이 선택 기준임 |
| `O(n^2)` 이상 | 단순 중첩 비교, 일부 DP | 입력 증가에 민감하므로 데이터 규모 제한, 가지치기, 인덱싱, 근사화 검토가 필요함 |
| 지수·팩토리얼 | 완전탐색, 순열 탐색 | 정확해도 대규모 적용이 어렵기 때문에 DP, 백트래킹, 휴리스틱, 근사 알고리즘 검토가 필요함 |

복잡도 표는 암기 항목이 아니라 요구사항에서 허용 가능한 입력 규모와 자원 한계를 역산하는 판단 도구임.

## 시간-공간 트레이드오프

시간과 공간은 독립 지표가 아니라 서로 교환되는 설계 자원임.

| 시간 절감 방식 | 증가하는 공간 비용 | 적용 판단 |
|:---|:---|:---|
| 해시 테이블·인덱스 구축 | 버킷, 인덱스, 메타데이터 | 조회가 반복되고 메모리 여유가 있을 때 유리함 |
| 동적 프로그래밍 메모이제이션 | 상태 테이블 | 중복 부분 문제가 많고 상태 수가 통제 가능할 때 유리함 |
| 캐시·전처리 결과 저장 | 캐시 메모리, 무효화 관리 비용 | 동일 질의 반복이 많고 갱신 빈도가 낮을 때 유리함 |
| 스트리밍·제자리 처리 | 반복 계산 또는 단순화된 연산 | 메모리가 병목이고 지연 요구가 완만할 때 유리함 |

따라서 답안에서는 "빠르다"가 아니라 "추가 공간을 사용해 어떤 반복 비용을 줄였는가" 또는 "공간을 줄이는 대신 어떤 계산을 반복하는가"를 명확히 써야 함.

## 오해와 감점 포인트

- **실행시간과 복잡도 혼동**: `O(n)` 알고리즘이 항상 `O(log n)` 알고리즘보다 빠른 것은 아니며, 작은 입력에서는 상수 계수와 캐시 지역성이 더 클 수 있음
- **입력 변수 단순화**: 그래프 알고리즘을 `n` 하나로만 쓰면 정점 `V`와 간선 `E`의 영향을 설명하지 못함
- **최악·평균 조건 누락**: 해시 조회 평균 `O(1)`, 퀵 정렬 평균 `O(n log n)`처럼 조건부 성능을 보장 성능처럼 쓰면 감점됨
- **입출력 병목 누락**: 외부 정렬, 분산 처리, 대용량 로그 분석에서는 CPU 연산보다 디스크·네트워크 비용이 지배적일 수 있음
- **공간복잡도 누락**: 재귀 스택, 임시 배열, DP 테이블, 인덱스 공간을 빼면 실제 운영 가능성을 판단하기 어려움

## 답안 작성 포인트

1. 정의는 "입력 증가에 따른 시간·메모리 증가율을 함수로 표현한 알고리즘 선택 기준"으로 시작함
2. 시간복잡도와 공간복잡도를 표로 구분하고, `T(n)`, `S(n)`, `O/Theta/Omega`를 함께 제시함
3. 분석 절차는 입력 변수 정의, 기본 연산 계산, 보조 공간 계산, 점근 표기, 요구사항 판단 순서로 씀
4. 예시는 단순히 `O(n)` 나열이 아니라 이진 탐색, 해시, 정렬, DP처럼 선택 조건이 달라지는 사례로 설명함
5. 결론은 "복잡도는 1차 필터이며, 최종 선택은 입력 분포·메모리·I/O·SLA 측정과 함께 결정한다"로 마무리함

> 기술사 관점에서 복잡도 분석은 수식 암기가 아니라, 데이터 증가에 따른 장애 가능성을 사전에 예측하고 알고리즘 선택의 근거를 제시하는 설계 판단 도구임.
