# 📖 【암기용】 개념 완전 이해

> 목적: 시간복잡도·공간복잡도를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 입력 크기 n 증가에 따른 실행 시간과 메모리 증가율
- **왜 필요한가**: 실제 초 단위 시간은 CPU·언어·I/O에 따라 달라진다. 복잡도는 구현 환경이 달라도 알고리즘의 자원 증가 패턴을 비교하게 해준다.
- **핵심 직관**: n이 10배가 될 때 연산 수와 메모리가 몇 배가 되는지 보는 척도임

## 깊이 이해
- **배경·문제의식**: 같은 문제라도 선형 탐색 O(n), 이진 탐색 O(log n), 완전탐색 O(2^n)은 n 증가 시 처리 가능한 입력 규모가 달라진다.
- **작동 원리**: 입력 크기 n에 대해 기본 연산 횟수를 함수 f(n)으로 세고, 최고차항 중심으로 시간복잡도를 표현한다. 추가 배열·재귀 스택·해시 저장소 등 입력 외 메모리 증가율은 공간복잡도로 표현한다.
- **비유**: 창고에서 물건을 찾을 때 전체 상자를 여는 방식은 n개 확인, 번호순 선반에서 절반씩 줄이는 방식은 log2 n번 확인이다.
- **구체 예시**: n=1,000,000일 때 O(n)은 100만회, O(log2 n)은 약 20회, O(n^2)은 10^12회로 1GHz 단순 연산 기준 약 1,000초(≈17분) 규모임.
- **흔한 오해·주의점**: 시간복잡도는 실제 실행시간 그 자체가 아니다. 캐시 미스·분기 예측·I/O 대기까지 포함한 벤치마크와 함께 판단해야 함.

## 연결 개념
- Big-O 표기법 — 상한 중심 증가율 표현
- 자료구조 선택 — 배열·해시·트리의 탐색 비용 비교
- 성능평가 — 이론 복잡도와 실제 p95 지연시간 검증 연결

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 시간복잡도·공간복잡도는 입력 크기 n 증가에 따른 CPU 연산량과 추가 메모리 증가율을 수학적으로 표현한 척도이다.
> 2. **가치**: n=10^6 이상 데이터에서 O(n log n)과 O(n^2)의 차이는 실행 가능 여부를 가르는 설계 기준이다.
> 3. **판단 포인트**: 평균·최악·상환 분석을 구분하고, 이론 복잡도와 캐시·I/O·동시성 병목을 함께 검증해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 입력 n에 따른 연산량·메모리 자원 증가율
- 배경: 기능이 동일한 알고리즘이라도 n이 증가할 때 연산량·메모리 증가율 차이가 실제 선택 기준이 됨
- 필요성: 대용량 로그·추천·검색 시스템에서 O(n^2) 설계는 트래픽 증가 시 지연시간이 급증할 수 있어, 도입 전 시간·공간 복잡도 분석이 필수

## Ⅱ. 구조 및 구성요소

```text
입력 n -> 기본 연산 f(n) -> 시간복잡도
       -> 추가 메모리 g(n) -> 공간복잡도
반복/재귀 구조 -> 최고차항 추출 -> 실측 지표 보정
```

| 구성요소 | 역할 | 판단 기준 |
|:---|:---|:---|
| 입력 크기 n | 데이터 개수·정점 수·문자열 길이 | n, V, E 등 변수 명시 |
| 기본 연산 | 비교·대입·해시 계산·간선 완화 | 최빈 실행 명령 기준 |
| 시간복잡도 | 연산 횟수 증가율 | O(1)~O(2^n) 계층 |
| 공간복잡도 | 추가 메모리 증가율 | 배열 O(n), 재귀 스택 O(log n) |

> 요약: 입력 크기·기본 연산·추가 메모리를 분리해 시간과 공간 증가율을 각각 산정함.

## Ⅲ. 동작원리 및 흐름도

```text
문제 입력 -> 반복/재귀 구조 파악 -> 기본 연산 카운트
        -> 최고차항 추출 -> 시간·공간복잡도 표기 -> 병목 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 변수 지정 | n, V, E, m 등 단위 분리 |
| 2 | 반복·재귀식 도출 | T(n)=2T(n/2)+n 등 |
| 3 | 하위 항·계수 제거, 최고차항만 잔존 | 3n^2+10n → O(n^2) |
| 4 | 추가 메모리 산정 | 보조 배열·스택·큐 포함 |
| 5 | 실측 대조 | p95 지연, 메모리 RSS, 캐시 미스 |

> 요약: 복잡도 분석은 입력 변수 지정에서 시작해 연산식·메모리식을 도출하고 실측 지표로 보정함.

## Ⅳ. 특징

| 구분 | 시간복잡도 | 공간복잡도 | 수치 예시 |
|:---|:---|:---|:---|
| 목적 | CPU 연산량 증가율 | 추가 메모리 증가율 | O(n log n), O(n) |
| 주요 병목 | 반복·재귀·정렬·탐색 | 배열·해시·재귀 스택 | n=10^6, int 배열 약 4MB |
| 트레이드오프 | 해시로 탐색 O(n)에서 O(1) 평균 | 해시 테이블 O(n) 추가 | load factor 0.75 |
| 한계 | I/O·캐시 영향 미반영 | 메모리 계층 지연 미반영 | L3 miss 10ns~40ns |

> 요약: 시간과 공간은 서로 교환되는 경우가 많아, 목표 지연시간과 메모리 예산을 함께 둬야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 복잡도 분석 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 구현 후 벤치마크만 수행 | 설계 단계에서 O(f(n)), O(g(n)) 산정 | n 최대값 10^5 이상이면 사전 분석 |
| 비용/성능 | 상수 최적화 중심 | 증가율 계층과 p95 지연 병행 | O(n^2) 후보는 SLA 200ms 기준 검증 |
| 운영/위험 | 입력 증가 시 장애 후 발견 | 입력 상한·메모리 상한을 설계서에 명시 | RSS·cache miss·TPS 동시 측정 |

> 요약: 복잡도 분석은 구현 전 후보 제거, 구현 후 실측 보정으로 이어질 때 설계 기준이 된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 입력 폭증 | n 상한 미정의 | n=10^5/10^6/10^9별 허용 복잡도 표 작성 | 최대 입력 처리시간 |
| 메모리 초과 | 보조 배열·재귀 스택 누락 | 공간복잡도와 RSS 예산 동시 산정 | RSS, OOM 발생 건수 |
| 이론·실측 불일치 | 캐시·I/O·동시성 영향 | JMH·perf·APM으로 p95·cache miss 측정 | p95 지연, cache miss ratio |

> 요약: 주요 위험은 입력 상한, 메모리, 하드웨어 병목 누락이며 수치 지표로 보정해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시간 증가율 | n 2배 증가 시 실행시간 증가 배율 기록 | 벤치마크 회귀 |
| 공간 증가율 | RSS가 메모리 예산 80% 이하 | 프로파일러, 컨테이너 메트릭 |
| 운영 지표 | p95 200ms 이하, 오류율 0.1% 이하 | APM, 부하 테스트 |

> 요약: 도입 후 성공 여부는 이론식, 메모리 증가율, p95 지연이 같은 방향으로 설명되는지로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 설계 단계: n 최대값 10^5·10^6·10^9별 허용 복잡도 표 작성, O(n^2) 후보는 사전 제외
2. 구현 단계: 해시·정렬·인덱스·메모이제이션 적용 시 시간 O(n^2)에서 O(n log n) 또는 O(n) 목표 설정
3. 검증 단계: JMH·pytest-benchmark·perf로 p50/p95 지연, RSS, cache-miss를 측정해 이론식과 대조

**결론 (2줄):**
- 기술사 판단: n이 작고 메모리 128MB 이하이면 공간 절약형, n≥10^6이면 시간복잡도 우선 설계 선택
- 향후 방향: 알고리즘 분석은 CPU·GPU·분산환경의 병렬도와 메모리 계층 비용까지 포함하는 비용 모델로 확장 필요
