## 미리 알고가기

- 입력 크기 $n$: 데이터 개수, 행렬 차원 등 분석 기준임
- 기본 연산: 비교·교환·대입처럼 반복되는 핵심 작업임
- 지배항: 증가율을 좌우하는 최고차항임
- 트레이드오프: 시간과 메모리의 상충 관계임

## Ⅰ. 개요

- **정의/개념**: 알고리즘 복잡도는 입력 크기별 시간·메모리 증가율임
- **배경/필요성**: 대용량 입력의 지연·메모리 한계 예측에 필요함

## Ⅱ. 특징

- HW·언어와 분리해 알고리즘 구조를 비교함
- 상수항과 하위 차수를 제거해 증가율을 봄
- 시간·공간 트레이드오프 선택 기준을 제공함

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| **분석 대상** | 입력 증가에 따른 기본 연산 수행 횟수 | 알고리즘 실행을 위해 추가로 필요한 메모리양 |
| **병목** | 지연 증가, 처리량 저하 | 메모리 부족, 스와핑, 캐시 미스 |
| **개선 방향** | 반복 축소, 메모이제이션, 탐색 제한 | 제자리 처리, 스트리밍, 버퍼 재사용 |

> 요약: 시간은 응답 한계, 공간은 메모리 한계를 판단함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 $n$ | 자원 사용량을 바꾸는 기준값임 |
| 기본 연산 | 시간을 지배하는 반복 작업임 |
| 비용 함수 $f(n)$ | 입력별 연산 수와 메모리 사용량 식임 |
| 점근 표기 | 상수와 하위항을 제거한 증가율 표기임 |

```text
[ 분석 구조 ]
+-----------+      +-----------+      +-----------+
| 입력 규모  | ---> | 연산/메모리 | ---> | 복잡도 도출 |
|   (n)     |      | 카운팅     |      |  (점근표기) |
+-----------+      +-----------+      +-----------+
```

> 요약: 입력 규모를 기준으로 비용을 세고 지배 증가율만 남김.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 연산 단위 식별 | --> | 비용 함수 산출 | --> | 최고차항 추출 | --> | 점근 표기 확정 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **단위 식별**: 시간 지배 연산과 보조 메모리를 정함
2. **함수 산출**: 반복 깊이와 재귀 수를 입력 $n$의 식으로 씀
3. **항 제거**: 상수와 낮은 차수 항을 제거함
4. **표기 확정**: $O(g(n))$으로 자원 증가율을 표시함

> 요약: 코드 구조를 비용 함수로 바꾼 뒤 지배항으로 표기함.

## Ⅵ. 실무 적용 및 유의점

1. 대규모 트래픽은 최악 입력 상한을 잡고 p99 지연·최대 메모리로 검증함
2. 캐싱은 TTL·LRU로 메모리를 통제하고 적중률·사용량을 확인함

## Ⅶ. 결론

- 알고리즘 복잡도는 입력 증가 시 시간·메모리 한계를 판단하는 선택 기준임

## 작성 근거(검토용)

- **개요 구성**: 시간과 공간을 함께 정의해야 알고리즘 선택이 단순 속도 비교로 축소되지 않음
- **특징 선정**: HW·언어 독립성, 지배항, 트레이드오프는 복잡도 분석의 판단 기준이라 남김
- **Ⅲ 비교축**: 시간은 지연, 공간은 메모리 병목을 가르므로 분석 대상·병목·개선 방향으로 정리함
- **구조 도식**: 입력 규모에서 비용 산출과 점근 표기로 이어지는 분석 순서를 보이기 위해 배치함
- **실무 유의점**: 최악 입력과 캐시 정책은 복잡도 판단이 운영 지표로 검증되는 대표 사례라 사용함
