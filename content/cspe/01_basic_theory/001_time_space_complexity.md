## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 시간 복잡도(Time Complexity)는 알고리즘이 입력 크기 N에 대해 수행하는 **기본 연산 횟수의 증가율**이고, 공간 복잡도(Space Complexity)는 같은 조건에서 **추가로 사용하는 메모리 양의 증가율**이다. 둘 다 절대적 수치가 아니라 N이 커질 때의 **성장 추세(Growth Rate)**를 측정한다.
> 2. **가치**: 하드웨어 성능·프로그래밍 언어·컴파일러 최적화 등 환경 변수를 배제하고, 알고리즘 자체의 **확장성(Scalability)**을 객관적으로 평가하는 유일한 수단이다. 클라우드 환경에서 자원 사용량 = 비용이므로 복잡도 분석은 곧 **비용 예측**이다.
> 3. **융합**: 데이터베이스 인덱스 설계(B-Tree O(log N) vs 풀 스캔 O(N)), 네트워크 라우팅 알고리즘(다익스트라 O(E log V)), 보안(암호 해독의 지수적 복잡도) 등 모든 CS 분야에서 알고리즘 선택의 근거가 된다.

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| **시간 복잡도(Time Complexity)** | 알고리즘이 입력 크기 $N$에 대해 수행하는 기본 연산 횟수의 증가율. $T(N)$으로 표기 | "요리에 걸리는 시간" |
| **공간 복잡도(Space Complexity)** | 알고리즘이 입력 크기 $N$에 대해 추가로 사용하는 메모리의 증가율. $S(N)$으로 표기 | "요리할 때 꺼내 쓰는 접시 수" |
| **Big-O $O(\cdot)$** | 최악의 경우 상한. $T(N) \leq c \cdot f(N)$을 만족하는 $f(N)$의 차수 | "최대 이만큼 걸린다" |
| **Big-Ω $\Omega(\cdot)$** | 최선의 경우 하한. 알고리즘이 아무리 빨라도 이보다 적은 연산은 불가 | "최소 이만큼은 걸린다" |
| **Big-Θ $\Theta(\cdot)$** | 상한과 하한이 동일한 차수일 때의 정확한 증가율 | "딱 이만큼 걸린다" |
| **마스터 정리(Master Theorem)** | $T(N) = aT(N/b) + f(N)$ 형태의 재귀 점화식을 닫힌 형태로 풀어주는 공식 | "재귀 복잡도 자동 계산기" |
| **분할 상환 분석(Amortized)** | 한 번의 비싼 연산을 여러 번의 싼 연산에 분배하여 평균 비용을 구하는 기법 | "할부 지불" |

## Ⅰ. 개요 및 필요성

- **개념**: 알고리즘의 효율성을 **입력 크기 $N$의 함수**로 표현하는 분석 기법이다. 시간 복잡도 $T(N)$은 기본 연산(대입·비교·산술)의 실행 횟수를, 공간 복잡도 $S(N)$은 알고리즘이 추가로 요구하는 메모리(입력 자체 제외)를 나타낸다. 점근적 표기법(Asymptotic Notation)으로 $O(\cdot)$, $\Omega(\cdot)$, $\Theta(\cdot)$를 사용하며, 실무에서는 **최악의 경우 상한(Big-O)**을 기준으로 판단한다.

- **필요성**: 같은 문제를 푸는 알고리즘이라도 $N=10$에서는 차이가 미미하지만 $N=1{,}000{,}000$에서는 $O(N^2)$과 $O(N \log N)$의 차이가 수만 배에 달한다. 프로덕션 시스템에서 데이터가 매년 10배씩 증가할 때, 알고리즘 선택 하나가 서버 비용 100만 원과 1억 원의 차이를 만든다.

- **비유**: 복잡도 분석은 자동차의 **연비 등급**과 같다. 시내 주행(N이 작을 때)에서는 SUV든 경차든 별 차이가 없지만, 장거리(N이 클 때)에서는 연비 차이가 주유비로 직결된다. 시간 복잡도는 주행 속도, 공간 복잡도는 트렁크 크기에 해당한다.

- **등장 배경 및 발전 과정**:
  1. **1960년대 — 점근적 분석의 탄생**: Donald Knuth가 "The Art of Computer Programming"에서 알고리즘 분석의 수학적 체계를 정립했다. 당시 컴퓨터 메모리가 수 KB에 불과했기에 공간 복잡도는 생존 문제였다.
  2. **1990~2000년대 — 시간 복잡도 중심 시대**: 메모리 가격이 급락하면서 "메모리를 써서 속도를 얻자"는 트레이드오프(Space-Time Tradeoff)가 보편화되었다. 해시 테이블, 메모이제이션, 캐시 등이 대표적이다.
  3. **2010년대~ — 공간 복잡도의 재부상**: 빅데이터 시대에 TB~PB 단위 데이터를 처리하면서, 메모리에 올릴 수 없는 데이터에 대한 스트리밍 알고리즘(O(1) 공간)이 다시 주목받고 있다.

```text
+-----------------------------------------------------------------------+
|            복잡도 클래스별 연산 횟수 증가 (N vs T(N))                  |
+-----------------------------------------------------------------------+
|                                                                       |
|  T(N)                                                                 |
|  ^                                                     O(2^N)         |
|  |                                                   /                |
|  |                                                 /                  |
|  |                                               /                    |
|  |                                        O(N²)/                      |
|  |                                          /                         |
|  |                                        /                           |
|  |                               O(N log N)                           |
|  |                              /                                     |
|  |                       O(N) /                                       |
|  |                         /                                          |
|  |              O(log N) /                                            |
|  |                    ./                                              |
|  | O(1)  ___________./___________________                             |
|  |____________________________________________________> N            |
|                                                                       |
|  N=10    N=100      N=1,000     N=10,000    N=100,000                 |
|  ----    -----      -------     --------    ---------                 |
|  O(1):       1          1          1            1            1        |
|  O(log N):   3          7         10           13           17        |
|  O(N):      10        100      1,000       10,000      100,000       |
|  O(N²):    100     10,000  1,000,000  100,000,000  → 메모리 초과!     |
|  O(2^N):  1024  → 10^30... 사실상 실행 불가                           |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 입력 크기 N이 증가할 때 각 복잡도 클래스의 연산 횟수가 어떻게 폭발적으로 차이 나는지를 보여준다. O(1)과 O(log N)은 N이 아무리 커져도 거의 일정하거나 매우 느리게 증가하는 반면, O(N²)은 N=10,000에서 이미 1억 회에 도달하고, O(2^N)은 N=100만 되어도 우주의 원자 수를 초과하는 연산을 요구한다. 데이터베이스에서 인덱스를 사용하면 O(N) 풀 스캔이 O(log N)으로 바뀌는 이유가 바로 이 차이에 있다. 클라우드 비용은 연산 횟수에 비례하므로, N=100,000일 때 O(N log N) 알고리즘은 O(N²) 대비 약 6,000배의 비용 절감을 가져온다.

- **📢 섹션 요약 비유**: 서울에서 부산까지 갈 때 O(1)은 순간이동, O(log N)은 KTX, O(N)은 자전거, O(N²)은 한 발짝 갈 때마다 처음으로 돌아가서 다시 시작하는 것과 같습니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 내부 동작 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **기본 연산(Primitive Operation)** | 분석의 최소 단위 | 대입, 비교, 산술, 배열 접근 등 상수 시간 O(1) 연산 | 모든 알고리즘 | 요리의 칼질 1회 |
| **반복문 분석** | 시간 복잡도의 핵심 결정 요인 | 단일 for → O(N), 중첩 for → O(N²), 절반 분할 → O(log N) | 정렬, 탐색 | 계단 오르기 vs 엘리베이터 |
| **재귀 분석(Recurrence Relation)** | 재귀 알고리즘의 복잡도 도출 | T(N) = aT(N/b) + f(N) 형태의 점화식을 마스터 정리로 해석 | 병합 정렬, 퀵 정렬, 분할 정복 | 러시아 인형(마트료시카) |
| **공간 측정** | 추가 메모리 사용량 추적 | 보조 배열, 재귀 호출 스택 깊이, 해시 테이블 크기 등을 합산 | 인플레이스 정렬, 메모이제이션 | 요리할 때 꺼내 쓰는 접시 수 |
| **점근적 표기법** | 복잡도를 간결하게 표현 | O(·) 상한, Ω(·) 하한, Θ(·) 상하한 동시 | 알고리즘 비교·선택 | 자동차 최대속도/최저속도/순항속도 |

### 코드에서 복잡도를 읽는 법

|              반복문 구조별 시간 복잡도 분석 패턴                       |
+-----------------------------------------------------------------------+
|                                                                       |
|  패턴 1: 단순 반복                                                    |
|  +------------------------------+                                     |
|  | for i in range(N):           |  → 본문이 O(1)이면                  |
|  |     상수 시간 연산            |  → 전체 = O(N)                     |
|  +------------------------------+                                     |
|                                                                       |
|  패턴 2: 이중 반복 (중첩)                                             |
|  +------------------------------+                                     |
|  | for i in range(N):           |                                     |
|  |   for j in range(N):         |  → O(N) × O(N)                     |
|  |     상수 시간 연산            |  → 전체 = O(N²)                    |
|  +------------------------------+                                     |
|                                                                       |
|  패턴 3: 절반 분할 반복                                               |
|  +------------------------------+                                     |
|  | while N > 1:                 |  → 매번 N을 절반으로                |
|  |     N = N / 2                |  → log₂N번 반복                    |
|  |     상수 시간 연산            |  → 전체 = O(log N)                 |
|  +------------------------------+                                     |
|                                                                       |
|  패턴 4: 순차 블록 (연속)                                             |
|  +------------------------------+                                     |
|  | O(N) 루프                    |  → O(N) + O(N²)                    |
|  | O(N²) 루프                   |  → 전체 = O(N²) (큰 쪽이 지배)    |
|  +------------------------------+                                     |
|                                                                       |
|  패턴 5: 재귀 (분할 정복)                                             |
|  +------------------------------+                                     |
|  | T(N) = 2T(N/2) + O(N)       |  → 마스터 정리 Case 2              |
|  | 예: 병합 정렬                 |  → 전체 = O(N log N)               |
|  +------------------------------+                                     |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 알고리즘의 시간 복잡도를 결정하는 것은 대부분 **반복문의 구조**이다. 단순 반복은 O(N), 중첩하면 O(N²)으로 곱해지며, 매번 범위를 절반으로 줄이면 O(log N)이 된다. 순차적으로 나열된 블록은 **덧셈**(가장 큰 항이 지배)이고, 중첩된 블록은 **곱셈**이다. 재귀 알고리즘은 점화식 T(N) = aT(N/b) + f(N)으로 표현한 뒤, 마스터 정리(Master Theorem)의 3가지 경우에 대입하면 닫힌 형태(Closed Form)의 복잡도를 구할 수 있다. 병합 정렬의 경우 a=2, b=2, f(N)=O(N)이므로 Case 2에 해당하여 T(N) = O(N log N)이 된다.

- **📢 섹션 요약 비유**: 반복문 분석은 건물 층수를 세는 것과 같습니다. 1층짜리 건물(단일 루프)이면 O(N), 2층짜리(이중 루프)이면 O(N²), 매번 엘리베이터로 절반 층을 건너뛰면 O(log N)입니다. 층수를 세면 복잡도가 보입니다.

## Ⅲ. 비교 및 연결

### 비교 1: 시간 복잡도 vs 공간 복잡도

| 비교 항목 | 시간 복잡도 (Time) | 공간 복잡도 (Space) |
|:---|:---|:---|
| **측정 대상** | 기본 연산 실행 횟수 | 추가 메모리 사용량 (바이트) |
| **최적화 목표** | 실행 시간 단축 → 사용자 응답 속도 | 메모리 절약 → OOM(Out of Memory) 방지 |
| **트레이드오프** | 메모리를 더 쓰면 시간을 줄일 수 있음 (캐시, 해시) | 시간을 더 쓰면 메모리를 줄일 수 있음 (재계산) |
| **실무 우선순위** | 대부분의 웹/앱 서비스에서 1순위 | 임베디드, 모바일, 빅데이터 스트리밍에서 1순위 |
| **클라우드 비용** | CPU 시간 과금 (Lambda, Cloud Run) | 메모리 크기 과금 (RAM 인스턴스 타입) |
| **대표 예시** | 퀵 정렬 O(N log N) vs 버블 정렬 O(N²) | 인플레이스 정렬 O(1) vs 병합 정렬 O(N) |

### 비교 2: 최선/평균/최악 케이스

| 비교 항목 | 최선 (Best) | 평균 (Average) | 최악 (Worst) |
|:---|:---|:---|:---|
| **의미** | 가장 유리한 입력 | 모든 가능한 입력의 기대값 | 가장 불리한 입력 |
| **표기** | Ω(·) 하한 | Θ(·) 평균 | O(·) 상한 |
| **퀵 정렬 예시** | Ω(N log N) 균등 분할 | Θ(N log N) 랜덤 입력 | O(N²) 이미 정렬된 배열 |
| **실무 기준** | 참고 수준 | 성능 예측에 활용 | **SLA 보장의 근거** |

### 과목 융합 관점
- **데이터베이스**: 인덱스를 걸면 테이블 풀 스캔 O(N)이 B-Tree 탐색 O(log N)으로 바뀌며, 이는 100만 행 기준 약 50,000배의 차이다. 쿼리 옵티마이저가 실행 계획을 선택하는 핵심 기준이 바로 복잡도 추정이다.
- **네트워크**: 라우팅 알고리즘(다익스트라 O((V+E) log V))의 복잡도는 네트워크 규모가 커질 때 수렴 시간을 결정하며, ISP 규모의 BGP 경로 계산에서 복잡도 차이가 장애 복구 시간을 좌우한다.
- **보안**: AES-256의 키 공간 탈취는 O(2²⁵⁶)이며 이는 현재 컴퓨팅 능력으로 우주의 수명보다 긴 시간이 소요된다. 암호 알고리즘의 안전성은 곧 공격 알고리즘의 **지수적 시간 복잡도**에 의존한다.

- **📢 섹션 요약 비유**: 시간 복잡도와 공간 복잡도는 자동차의 속도와 트렁크 크기입니다. 경주차(시간 최적)는 빠르지만 짐을 못 싣고, 트럭(공간 최적)은 많이 실을 수 있지만 느립니다. 어떤 차를 탈지는 목적지(문제의 성격)에 달려 있습니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — 전자상거래 검색 엔진의 정렬 알고리즘 선택**: 일 평균 500만 건의 상품 검색 결과를 정렬해야 하는 시스템에서, 초기에 O(N²)인 버블 정렬을 사용했다가 트래픽 증가로 응답 시간이 5초를 초과했다. O(N log N)인 Tim Sort(Python 기본 정렬)로 교체한 결과, 500만 건 기준 연산 횟수가 25조 회에서 1.1억 회로 감소하여 응답 시간이 200ms 이내로 개선되었다.

2. **시나리오 — 메모리 제약 임베디드 시스템에서의 공간 최적화**: IoT 센서 디바이스(RAM 64KB)에서 24시간 센서 데이터를 수집·분석해야 한다. 전체 데이터를 배열에 저장하면 O(N) 공간이 필요하여 메모리가 부족하다. 슬라이딩 윈도우 기법(O(1) 공간)으로 최근 1분 데이터만 유지하며 이동 평균을 계산하는 스트리밍 알고리즘으로 전환하여 64KB 이내에서 안정적으로 동작하게 만들었다.

```text
+-----------------------------------------------------------------------+
|           알고리즘 선택 의사결정 플로우                                |
+-----------------------------------------------------------------------+
|                                                                       |
|  [문제 정의: 입력 크기 N은?]                                          |
|       |                                                               |
|       v                                                               |
|  N < 1,000인가?                                                       |
|    +- 예 → O(N²)도 수용 가능 (단순 구현 우선)                         |
|    +- 아니오 →                                                        |
|         |                                                             |
|         v                                                             |
|    메모리 제약이 있는가?                                              |
|      +- 예 → 인플레이스 알고리즘 선택 (공간 O(1))                    |
|      |        힙 정렬, 슬라이딩 윈도우                                 |
|      +- 아니오 →                                                      |
|           |                                                           |
|           v                                                           |
|      최악 케이스 보장이 필요한가?                                     |
|        +- 예 → 최악 O(N log N) 보장 알고리즘                         |
|        |        병합 정렬, 힙 정렬                                     |
|        +- 아니오 →                                                    |
|             |                                                         |
|             v                                                         |
|        평균 성능 최적화                                               |
|        퀵 정렬 (평균 O(N log N), 최악 O(N²))                         |
|        + 랜덤 피벗으로 최악 확률 최소화                               |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 알고리즘 선택은 입력 크기, 메모리 제약, 최악 케이스 보장 필요 여부라는 세 가지 축으로 의사결정한다. N이 작으면 단순한 O(N²) 알고리즘이 캐시 효율과 구현 단순성에서 유리할 수 있다. 메모리가 제한된 임베디드 환경에서는 추가 공간 O(1)인 인플레이스 알고리즘이 필수다. SLA에 최악 응답 시간이 명시된 시스템에서는 퀵 정렬의 O(N²) 최악 케이스를 감수할 수 없으므로 병합 정렬이나 힙 정렬을 선택한다.

### 도입 체크리스트
- **기술적**: 핵심 비즈니스 로직의 반복문 중첩 깊이와 재귀 호출 패턴을 분석했는가? 입력 크기 N의 현재 값과 향후 3년간 예상 증가율을 파악했는가?
- **운영 및 보안적**: 성능 프로파일링 도구(APM)로 실제 병목 지점을 측정한 후 최적화하고 있는가? 최악 케이스 입력을 의도적으로 만들어 테스트(Adversarial Testing)했는가?

### 안티패턴
- **조기 최적화(Premature Optimization)**: Donald Knuth의 경고 — "조기 최적화는 모든 악의 근원이다." 프로파일링 없이 직관에 의존한 최적화는 코드 가독성을 해치고 실제 병목은 다른 곳에 있는 경우가 많다. 반드시 **측정 후 최적화** 원칙을 따른다.
- **공간 복잡도 무시**: 시간 복잡도만 보고 메모이제이션을 무분별하게 적용하면 O(N) 또는 O(N²)의 추가 메모리가 발생하여 프로덕션에서 OOM(Out of Memory) 크래시를 유발한다. 특히 재귀 깊이가 O(N)인 알고리즘은 스택 오버플로우 위험이 있다.

- **📢 섹션 요약 비유**: 알고리즘 선택은 이사할 때 운송 수단 고르기와 같습니다. 짐이 적으면(N이 작으면) 택시면 되지만, 짐이 많으면(N이 크면) 5톤 트럭이 필요합니다. 그리고 엘리베이터 없는 5층(메모리 제약)이면 짐을 한 번에 다 못 올리니 나눠 올려야(인플레이스) 합니다.

| **정량** | O(N²) 알고리즘 사용, N=100만 시 1조 연산 | O(N log N) 사용, 2천만 연산 | 연산 횟수 **50,000배** 감소 |

| **정성** | "왜 느린지 모르겠다" 식 디버깅 | 병목 원인을 논리적으로 예측 | 장애 대응 시간 **1/10**로 단축 |

### 미래 전망
- **양자 컴퓨팅의 복잡도 혁명**: 그로버 알고리즘은 비정렬 탐색을 $O(N)$에서 $O(\sqrt{N})$으로, 쇼어 알고리즘은 소인수분해를 지수 시간에서 다항 시간으로 줄인다. 양자 컴퓨팅이 실용화되면 기존의 복잡도 기반 보안 체계(RSA)가 재설계되어야 한다.
- **AI 시대의 복잡도**: LLM 추론 비용은 토큰 수 $N$에 대해 트랜스포머 어텐션이 $O(N^2)$이다. FlashAttention 등 $O(N)$ 근사 기법이 연구되고 있으며, 이는 곧 AI 서비스의 비용 구조를 결정한다.

### 참고 표준
- **Knuth, "The Art of Computer Programming" (1968~)**: 알고리즘 분석의 수학적 기초 정립
- **Cormen et al., "Introduction to Algorithms" (CLRS)**: 마스터 정리, 분할 상환 분석 등 현대적 분석 기법의 표준 교과서
- **IEEE/ACM Computing Curricula**: 복잡도 분석을 CS 핵심 과목으로 지정

복잡도 분석은 단순히 학문적 도구가 아니라, 프로덕션 시스템의 확장성(Scalability)과 비용 효율(Cost Efficiency)을 결정하는 **엔지니어링 의사결정의 근거**이다. 알고리즘을 선택할 때 "N이 10배 커지면 어떻게 되는가?"라는 질문에 정량적으로 답할 수 있어야 하며, 이것이 기술사 수준의 판단력이다.

- **📢 섹션 요약 비유**: 복잡도 분석 없이 시스템을 설계하는 것은 건물 설계 시 하중 계산 없이 철근을 넣는 것과 같습니다. 2층집에서는 문제없어 보이지만, 20층을 올리면 무너집니다.

### 👶 어린이를 위한 3줄 비유 설명

1. 시간 복잡도는 "숨은그림찾기를 몇 번 들여다봐야 다 찾을 수 있는지"를 세는 거예요. 그림이 클수록(N이 클수록) 더 많이 봐야 해요.
2. 공간 복잡도는 "숨은그림찾기를 풀 때 메모 종이를 몇 장 쓰는지"예요. 메모 없이 머릿속으로만 풀면 공간은 O(1)이에요.
3. 좋은 알고리즘은 그림이 아무리 커져도 찾는 횟수가 조금만 늘어나는 방법(O(log N))이에요. 나쁜 알고리즘은 그림이 2배 커지면 찾는 횟수가 4배로 늘어나요(O(N²)).
