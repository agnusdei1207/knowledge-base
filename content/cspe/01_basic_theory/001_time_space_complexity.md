## 미리 알고가기

- 입력 크기 $n$: 데이터 개수나 행렬 차원처럼 비용 함수 산출의 기준이 되는 값임
- 기본 연산: 비교·교환·대입처럼 실행 횟수 산정의 기준이 되는 반복 작업임
- 보조 공간: 입력 저장 공간을 제외하고 알고리즘이 추가로 사용하는 메모리임
- 지배항: 큰 입력에서 비용 증가율을 결정하는 항임
- 트레이드오프: 시간을 줄이려고 메모리를 더 쓰거나 메모리를 줄이려고 시간을 더 쓰는 상충 관계임
- 빅오 $O(f(n))$: 입력이 커질 때 비용 함수의 점근 상한을 나타내는 표기임

## 쉽게 이해하기
- 이삿짐이 2배로 늘면 트럭 대수와 나르는 시간이 얼마나 늘어나는지 가늠하는 것과 같음
- 어떤 컴퓨터·언어로 옮기든 상관없이, 짐(입력)이 커질수록 시간·공간이 느는 패턴 자체를 비교하는 기준임

## 작성 근거(검토용)

- **개요 구성**: 정의에 연산량과 메모리 사용량 증가율을 함께 담아 시간·공간복잡도를 하나의 판단 기준으로 제시함
- **Ⅱ. 특징 선정**: 구현 환경과 분리한 증가율, 비용 함수, 지배항, 트레이드오프는 알고리즘 선택을 바꿈
- **Ⅲ. 비교축 선정**: 시간과 공간의 측정 대상, 산출값, 주요 위험이 자원 한계를 구분하므로 세 축으로 정리함
- **Ⅳ. 구조 선정**: 입력 크기와 기본 연산을 기준으로 시간 비용과 공간 비용을 분리하고, 점근 표기로 증가율을 비교하도록 구성함
- **Ⅴ. 절차 선정**: 비용 단위 식별에서 점근 표기 확정까지 이어지는 흐름이 분석 절차 자체이므로 별도 절로 둠
- **Ⅵ. 실무 사례 선정**: 로그 검색과 반복 계산 서비스는 시간·공간복잡도 분석을 운영 지표로 검증하는 대표 사례라 남김

## Ⅰ. 개요

- **정의/개념**: 시간·공간복잡도는 입력 크기에 따른 연산량과 메모리 사용량의 증가율을 나타내는 기준임
- **배경/필요성**: 구현 전 병목·자원 한계 예측을 위해 입력 크기별 연산량·메모리 증가율 분석이 필요함

## Ⅱ. 특징

- 하드웨어와 구현 언어의 차이를 제외하고 알고리즘 구조의 증가율을 비교함
- 반복문 깊이·재귀 분기·자료구조 접근이 비용 함수를 결정함
- 지배항 중심 표기로 입력 증가에 따른 자원 사용량 추세를 드러냄
- 시간과 공간의 트레이드오프에서 어떤 자원을 더 쓸지 선택하는 근거가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 (Time Complexity) | 공간복잡도 (Space Complexity) |
|:---|:---|:---|
| **측정 대상** | 기본 연산 수행 횟수 | 전체 메모리 사용량 |
| **산출값** | 입력 크기별 연산 횟수 증가율 | 입력 크기별 메모리 사용량 증가율 |
| **주요 위험** | 응답 시간 한계 초과 | 사용 가능 메모리 고갈 |

> 요약: 시간복잡도는 연산 횟수 증가율로 응답 시간 한계를, 공간복잡도는 메모리 증가율로 자원 고갈 위험을 판단함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 입력 크기 $n$ | 연산량과 메모리 사용량 변화의 기준 변수 |
| 기본 연산 | 시간 비용을 산정하는 반복 작업 단위 |
| 시간 비용 $T(n)$ | 입력 크기별 기본 연산의 실행 횟수 |
| 공간 비용 $S(n)$ | 입력 공간과 알고리즘이 추가로 쓰는 보조 공간의 합 |
| 점근 표기 | 지배항 기준의 자원 증가율 표현 |

> 요약: 복잡도 분석은 입력 크기별 시간 비용과 공간 비용을 분리해 계산하고 지배항으로 증가율을 표현함.

## Ⅴ. 원리 및 절차 흐름도

```text
입력 크기 정의 → 기본 연산·저장 단위 식별
                            ↓
                    시간·공간 함수 산출
                            ↓
                    지배항 → 점근 표기
```

1. **단위 식별**: 반복 횟수를 셀 기본 연산과 입력 외 보조 메모리를 정함
2. **함수 산출**: 연산 횟수와 보조 메모리 사용량을 각각 $n$의 식으로 씀
3. **지배항 추출**: 큰 입력에서 영향이 작은 상수와 하위항을 제거함
4. **표기 확정**: $O(f(n))$ 표기를 지연·메모리 한계와 연결함

> 요약: 연산량과 메모리 사용량을 비용 함수로 나타내고 지배항을 복잡도로 표시함.

## Ⅵ. 실무 사례

1. 대량 로그 검색은 선형 탐색 대신 색인을 적용해 조회 범위를 줄임
2. 반복 계산 서비스는 이전 결과를 캐시에 저장해 같은 연산을 다시 수행하지 않음

## Ⅶ. 결론

- 시간·공간복잡도는 입력 증가에 따른 지연과 메모리 한계를 예측해 구현 전 알고리즘을 선택하는 기준임
- 예상 최대 입력을 기준으로 전환 임계값을 정하고, 시간과 메모리 중 시스템 병목 자원을 우선 최적화해야 함
