## 미리 알고가기

- 입력 크기 `n`: 배열 원소 수, 문자열 길이, 그래프 정점·간선 수처럼 알고리즘 비용을 좌우하는 규모임
- 기본 연산: 비교, 대입, 교환, 산술 연산처럼 실행 횟수를 세는 기준 동작임
- 시간복잡도 `T(n)`: 벽시계 시간 자체가 아니라 입력 크기에 따라 기본 연산 횟수가 증가하는 양상임
- 공간복잡도 `S(n)`: 입력 저장 공간과 별도로 알고리즘 수행 중 추가로 필요한 메모리 사용량임
- 점근 분석: 작은 입력의 우연한 차이보다 큰 입력에서 지배적인 증가율을 비교하는 방식임

## Ⅰ. 개요

- **정의**: 시간복잡도와 공간복잡도는 알고리즘이 입력 크기 `n` 증가에 따라 기본 연산을 얼마나 더 수행하고, 추가 메모리를 얼마나 더 사용하는지 함수로 표현해 확장성을 판단하는 분석 기준임
- **배경/필요성**: 같은 기능을 수행하는 알고리즘이라도 데이터가 커지면 실행시간과 메모리 사용량이 다르게 증가함. 따라서 구현 전에 입력 규모를 기준으로 후보 알고리즘의 비용 증가율을 비교해야 함
- **비유**: 같은 배송 업무라도 물량이 10배 늘 때 차량 운행 횟수와 창고 면적이 얼마나 늘어나는지를 미리 계산하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘 선택 기준을 비용 증가율 관점에서 설명하는 역량 확인 | `T(n)`, `S(n)`, 기본 연산, 보조 공간, 최악·평균·최선, 시간-공간 트레이드오프 | 실행시간 초 단위 단정, 시간·공간 구분 누락, Big-O만 나열 |

> 요약: 복잡도 분석은 알고리즘을 실행해 본 결과가 아니라 입력 규모 변화에 따른 시간·메모리 비용 증가율을 예측하는 기준임.

## Ⅱ. 특징/비교

| 판단 기준 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 분석 대상 | 비교·대입·교환 등 기본 연산 횟수의 증가율 | 배열·해시·재귀 스택 등 추가 메모리 사용량의 증가율 |
| 설계 질문 | 이 알고리즘이 응답시간·처리량 요구를 만족하는가 | 이 알고리즘이 메모리 한계와 동시 처리량을 감당하는가 |
| 대표 충돌 | 인덱스·캐시·전처리로 시간을 줄이면 저장 공간이 늘 수 있음 | 보조 공간을 줄이면 반복 계산이나 탐색 시간이 늘 수 있음 |

> 요약: 시간복잡도와 공간복잡도는 분리해 계산하지만 실제 설계에서는 서로 교환되는 비용으로 함께 판단해야 함.

- 복잡도는 `O(n)`, `O(n log n)`, `O(n^2)`처럼 증가율을 비교하므로 입력이 커질수록 알고리즘 간 차이를 크게 드러냄
- 같은 `O(n)`이라도 기본 연산 종류, 메모리 접근 패턴, 캐시 적중률에 따라 실제 지연은 달라질 수 있음
- 답안에서는 표기 암기보다 "이 요구사항에서 왜 이 복잡도의 알고리즘을 선택하는가"를 설명해야 함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력규모 | ---> | 비용함수 | ---> | 점근표현 |
| n,V,E    |      | T(n),S(n)|      | O,Theta |
+----------+      +----------+      +----------+
                         |
                         v
                   +----------+
                   | 선택근거 |
                   +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 규모 | 비용을 좌우하는 데이터 크기를 `n`, `V`, `E` 등으로 정한 분석 변수임 | 처리해야 할 물량 |
| 기본 연산 | 반복문·재귀에서 가장 자주 수행되어 시간 비용을 대표하는 비교·교환·대입 연산임 | 물건 하나를 옮기는 손동작 |
| 보조 공간 | 입력 자체를 제외하고 알고리즘이 추가로 사용하는 배열, 큐, 스택, 해시 공간임 | 작업 중 임시로 쓰는 보관함 |
| 점근 표현 | 비용 함수에서 큰 입력의 증가율을 지배하는 항을 남겨 비교 가능하게 만든 표기임 | 먼 거리에서 보는 지형 지도 |

> 요약: 복잡도 분석은 입력 규모를 정하고 시간 비용과 공간 비용을 함수로 표현한 뒤 점근 표기로 선택 근거를 만드는 구조임.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 입력정의 | ---> | 연산/공간계산 | ---> | 차수정리 | ---> | 설계판단 |
+----------+      +----------+      +----------+      +----------+
```

1. **입력 정의**: 배열 길이 `n`, 그래프 정점 `V`, 간선 `E`처럼 비용을 좌우하는 변수를 정함
2. **연산·공간 계산**: 반복 횟수, 재귀 호출 깊이, 임시 배열 크기를 `T(n)`, `S(n)`으로 표현함
3. **차수 정리**: 큰 입력에서 지배적인 항을 중심으로 `O`, `Theta`, `Omega` 표기를 구분함
4. **설계 판단**: 응답시간 목표, 메모리 한계, 데이터 증가 전망을 기준으로 알고리즘을 선택함

> 요약: 복잡도 분석은 입력 변수를 정한 뒤 시간·공간 비용을 계산하고 운영 요구사항에 맞는 선택으로 연결하는 과정임.

## Ⅴ. 문제점

- **P1 추상 모델 한계**: 복잡도는 상수 계수, 캐시 적중, 분기 예측, I/O 대기 시간을 제거하므로 실제 지연과 차이가 생길 수 있음
- **P2 사례 범위 혼동**: 최악·평균·최선 조건을 구분하지 않으면 퀵정렬 평균 `O(n log n)`을 항상 보장되는 성능으로 오해함
- **P3 트레이드오프 누락**: 시간만 줄이거나 공간만 줄이는 선택은 메모리 비용, 캐시 효율, 장애 복구 비용을 놓칠 수 있음

> 요약: 복잡도는 강한 1차 판단 기준이지만 실제 환경과 입력 조건을 함께 보지 않으면 알고리즘 선택 오류가 발생함.

## Ⅵ. 개선방안

1. **단기**: 후보 알고리즘의 `T(n)`, `S(n)`, 최악·평균·최선 조건을 같은 기준으로 정리함
2. **중기**: 대표 입력과 경계 입력으로 벤치마크를 수행해 p95 지연, 메모리 피크, 캐시 미스 등으로 검증함
3. **장기**: 데이터 규모, 하드웨어, 운영 SLA별 알고리즘 선택 기준을 아키텍처 표준으로 관리함

- **P1 대응**: 이론 복잡도와 프로파일링 결과를 함께 기록함 (확인: p95 지연, 메모리 피크)
- **P2 대응**: 최악·평균·최선 조건과 입력 분포를 표기 옆에 명시함 (확인: 정렬·역정렬·랜덤 입력 테스트)
- **P3 대응**: 시간-공간 트레이드오프를 의사결정 기준에 포함함 (확인: SLA와 비용 기준 충족)

> 요약: 복잡도는 벤치마크와 운영 기준을 결합할 때 실제 알고리즘 선택 근거가 됨.

## Ⅶ. 전망

- **발전 방향**: 데이터 규모가 커질수록 단일 시간복잡도보다 메모리 계층, 네트워크 전송, 병렬 처리 비용을 함께 보는 다차원 분석이 중요해짐
- **기술사적 판단**: 엣지·모바일 환경에서는 공간복잡도와 전력 사용량이 알고리즘 채택 조건으로 결합될 가능성이 큼
- **기술사 제언**: 기술사는 복잡도 표기 자체보다 요구사항, 데이터 분포, 운영 제약을 연결해 알고리즘 선택 근거를 제시해야 함
