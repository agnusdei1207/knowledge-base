## 미리 알고가기

- 점근 표기: 입력 크기 $n$이 커질 때 증가율만 남겨 복잡도를 표현하는 방법임
- 지배항: 복잡도 함수에서 증가율을 사실상 결정하는 최고차항임
- 보조 공간: 입력 데이터 자체를 제외하고 알고리즘이 추가로 사용하는 메모리임
- 기본 연산: 비교, 대입, 재귀 호출처럼 비용을 셀 때 기준이 되는 작업 단위임
- 제자리 처리: 추가 배열을 새로 만들지 않고 입력 배열 자체의 공간에서 값을 바꿔가며 처리하는 방식임

## Ⅰ. 개요

- **정의/개념**: 시간복잡도는 입력 크기 $n$이 커질 때 알고리즘이 수행해야 하는 핵심 연산 수가 어떤 비율로 늘어나는지 나타내는 기준이며, 공간복잡도는 같은 상황에서 입력 외에 추가로 필요한 메모리가 얼마나 늘어나는지 나타내는 기준임
- **배경/필요성**: 같은 기능을 구현해도 데이터 규모가 커지면 CPU(Central Processing Unit) 시간보다 메모리 부족이 먼저 병목이 될 수 있으므로, 설계 단계에서 확장성과 자원 한계를 함께 판단할 기준이 필요함

## Ⅱ. 특징

- 시간복잡도는 입력이 커질수록 처리 지연이 얼마나 가파르게 늘어나는지 보여줌
- 공간복잡도는 임시 배열, 큐, 재귀 스택 때문에 메모리가 어디서 커지는지 드러냄
- 두 복잡도는 메모리를 더 써 시간을 줄일지, 메모리를 아껴 시간을 더 쓸지 같은 설계 절충을 설명하는 기준이 됨
- 실제 운영에서는 평균값보다 최악 경우를 함께 봐야 응답 상한과 메모리 한계를 미리 예측할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 무엇을 세는가 | 비교, 반복, 재귀 호출처럼 실제로 수행하는 핵심 연산 수를 기준으로 판단함 | 임시 배열, 큐, 재귀 스택처럼 입력 외에 추가로 잡는 메모리를 기준으로 판단함 |
| 운영에서 먼저 드러나는 한계 | 응답 지연, 타임아웃, 처리량 감소처럼 시간이 늘어나는 형태로 먼저 드러남 | 메모리 부족, 스와핑 증가, 캐시 적중률 저하처럼 메모리 압박 형태로 먼저 드러남 |
| 주로 줄이는 방법 | 중첩 반복을 줄이거나 탐색 범위를 줄여 연산 수 자체를 낮춤 | 제자리 처리, 버퍼 재사용, 스트리밍 처리로 추가 메모리 사용량을 낮춤 |
| 대표 판단 예 | $O(n^2)$ 알고리즘을 $O(n \log n)$ 구조로 바꿀지 판단할 때 사용함 | $O(n)$ 보조 배열을 없애고 $O(1)$ 추가 공간으로 줄일지 판단할 때 사용함 |

> 요약: 시간복잡도는 연산 증가율을, 공간복잡도는 추가 메모리 증가율을 보여주므로 둘을 함께 봐야 실제 병목을 놓치지 않음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 $n$ | 원소 수, 정점 수, 행 수처럼 문제 규모를 나타내는 변수이므로 무엇을 $n$으로 둘지 먼저 분명히 해야 함 |
| 기본 연산 | 비교, 교환, 해시 조회, 재귀 호출처럼 비용을 세는 단위이므로 어떤 연산을 지배 연산으로 볼지 잘못 잡으면 전체 분석이 흔들림 |
| 보조 저장소 | 입력 데이터 자체는 제외하고 임시 배열, 호출 스택, 큐처럼 추가로 잡는 공간을 세야 실제 메모리 부담을 놓치지 않음 |
| 분석 시나리오 | 최선, 평균, 최악 가운데 어떤 조건을 기준으로 볼지 정하는 항목이며 운영 시스템은 보통 최악 경우를 먼저 확인함 |

> 요약: 복잡도 분석은 입력 변수, 비용 단위, 보조 공간, 분석 조건을 먼저 고정해야 같은 알고리즘도 일관되게 비교할 수 있음

```text
+-----------+
| 입력 크기 n |
+-----------+
      |
      +-----------------------+
      |                       |
      v                       v
+--------------+      +----------------+
| 연산 카운트   |      | 보조 공간 카운트 |
| T(n)         |      | S(n)           |
+--------------+      +----------------+
      |                       |
      v                       v
+--------------+      +----------------+
| 지배항 추출   |      | 지배항 추출     |
| 시간복잡도 O  |      | 공간복잡도 O    |
+--------------+      +----------------+
      |                       |
      +-----------+-----------+
                  v
          +------------------+
          | 시간-공간 절충 판단 |
          +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 기준식별 | --> | 함수화   | --> | 경우구분 | --> | 표기환산 |
+----------+     +----------+     +----------+     +----------+
```

1. **기준 식별**: 알고리즘의 입력 크기 $n$과 무엇을 기본 연산으로 셀지, 무엇을 보조 공간으로 볼지 정함
2. **함수화**: 반복문·재귀 호출·임시 자료구조 사용을 추적해 연산 횟수는 $T(n)$으로, 추가 메모리량은 $S(n)$으로 세움
3. **경우 구분**: 입력 분포에 따라 최선·평균·최악 경우가 달라지므로 어떤 경우를 기준으로 지표를 확정할지 검증함
4. **표기 환산**: $T(n)$과 $S(n)$에서 지배항만 남겨 점근 표기로 바꾸고, 실측 실행 시간·메모리 사용량과 대조해 결과를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 대용량 데이터 정렬에서는 병합 정렬이 $O(n \log n)$ 시간을 보장하지만 병합 과정에서 $O(n)$ 보조 공간이 추가로 필요하므로, 메모리 제약이 큰 환경에서는 제자리 처리가 가능한 힙 정렬이나 퀵 정렬로 대체하고 최대 힙 사용량과 실행 시간을 함께 측정해 적합성을 확인함
2. 동적 계획법에서 재귀 호출마다 같은 부분 문제를 반복 계산하면 시간복잡도가 지수적으로 커지므로, 계산 결과를 저장해두는 캐싱 테이블로 시간을 줄이되 테이블 크기만큼 늘어나는 보조 공간은 상태 압축이나 슬라이딩 윈도우로 줄이고 테이블 크기와 캐시 적중률로 효과를 확인함

## Ⅶ. 결론

시간복잡도와 공간복잡도는 한쪽을 줄이면 다른 쪽이 늘어나는 상충 관계이므로, 알고리즘 설계는 두 지표를 함께 계산해 운영 환경에서 시간과 메모리 중 어느 자원이 먼저 한계에 부딪히는지를 기준으로 절충점을 선택하는 판단임.
