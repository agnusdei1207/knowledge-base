## Ⅰ. 개요

- **개요**: 입력 크기 `N`에 따른 알고리즘의 연산 횟수·메모리 사용량 증가율 측정 지표
- **배경/필요성**: 같은 알고리즘도 실행 하드웨어·언어·컴파일러에 따라 초 단위 실행 시간이 달라지므로, 환경에 무관하게 알고리즘 자체를 비교할 정량 지표가 필요함
- **출제 의도**: 시간복잡도 `T(N)`과 공간복잡도 `S(N)`이 각각 무엇을 측정하는지, 케이스(최선/평균/최악)에 따라 값이 달라지는 이유를 구조적으로 설명할 수 있는지 확인
- **답안 방향**: (1) `T(N)`·`S(N)`의 측정 대상 구분, (2) 최선/평균/최악 케이스별 판단 기준, (3) 시간-공간 트레이드오프에 기반한 실무 선택 기준

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 복잡도 개념과 측정 대상 설명 | `T(N)`(연산 횟수)·`S(N)`(추가 메모리) 구분, 최선/평균/최악 케이스 구분, 시간-공간 트레이드오프 | 점근적 표기법(`O`/`Ω`/`Θ`) 세부 정의와 혼동, 최고차항만 남기는 근거 누락 |

> 요약: 이 문제는 알고리즘의 자원 소비를 `N`의 함수로 정량 분석하고 트레이드오프를 판단하는 역량을 확인하려는 것임.

## Ⅱ. 구조 및 구성요소

```text
알고리즘 코드 -> 기본연산 식별 -> 반복/재귀 구조 분석 -> T(N) 산정
                                        |
                                        +-> 추가 메모리 사용 분석 -> S(N) 산정
                                                |
                                                +-> 케이스 구분(최선/평균/최악)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 기본연산(Primitive Operation) | 시간복잡도 측정의 최소 단위 | 대입·비교·산술 1회 실행 |
| 반복·재귀 구조 | `T(N)`을 결정하는 핵심 요인 | 단일 반복 `N`, 중첩 반복 `N^2`, 재귀는 점화식 `T(N)=aT(N/b)+f(N)` |
| 추가 메모리(Auxiliary Space) | `S(N)` 측정 대상(입력 자체는 제외) | 보조 배열·재귀 호출 스택·해시 테이블 크기 |
| 최선/평균/최악 케이스 | 입력 분포에 따른 시나리오 구분 | 시험 난이도의 하/중/상 |
| 공간-시간 트레이드오프 | 자원 배분 설계 기준 | 캐시·메모이제이션으로 시간을 아끼는 대신 메모리를 씀 |

> 요약: 시간복잡도는 반복·재귀 구조에서, 공간복잡도는 추가 메모리 사용에서 각각 별도로 산정함.

## Ⅲ. 동작원리 및 흐름도

```text
연산 단위 식별 -> 연산/메모리 횟수 카운트 -> 입력분포별 케이스 산정 -> 지배항 기준 등급화
```

- 1단계 [연산 단위 식별]: 대입·비교·산술 등 `O(1)` 단위 연산과, 추가로 할당되는 메모리 단위를 식별함
- 2단계 [횟수 카운트]: 반복문·재귀 호출 구조에서 `N`에 대한 연산 실행 횟수 `T(N)`과 추가 메모리 `S(N)`을 각각 셈함
- 3단계 [케이스 구분]: 입력 분포에 따라 최선(`Ω`)·평균(`Θ`)·최악(`O`) 실행 횟수를 구분해 산정함(각 표기의 수학적 정의는 002 참조)
- 4단계 [등급화]: `N`이 충분히 커질 때 지배적인 항만 남겨 자원 증가율 등급을 확정함

> 요약: 연산 단위 식별부터 케이스 구분, 지배항 등급화까지 4단계로 `T(N)`·`S(N)`을 도출함.

## Ⅳ. 특징

- 환경 독립성: 하드웨어·언어·컴파일러와 무관하게 알고리즘 자체의 자원 증가 추세만 비교함
- 트레이드오프 존재: 시간과 공간은 서로 맞바꿀 수 있는 자원이며, 한쪽을 아끼면 다른 쪽이 늘어남(예: 해시 인덱스는 `S(N)`을 늘려 탐색 `T(N)`을 줄임)
- 케이스 의존성: 동일 알고리즘도 입력 분포에 따라 `T(N)`이 달라짐(퀵 정렬은 평균 `N log N`, 최악 `N^2`)
- 상수·저차항 무시의 전제: `N`이 충분히 클 때만 유효한 비교이므로 `N`이 작으면 상수 계수가 실측 성능을 좌우함

> 요약: 시간·공간 복잡도는 환경 독립적 비교 지표이지만, 트레이드오프·케이스 의존성·`N`의 크기 조건을 함께 판단해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 시간 우선 설계 | 공간 우선 설계 | 선택 기준 |
|:---|:---|:---|:---|
| 대표 기법 | 캐싱·메모이제이션·해시 인덱스 | 인플레이스 알고리즘·스트리밍 처리 | 응답시간 SLA와 메모리 상한 중 지배적 제약으로 판단 |
| 트레이드오프 | 메모리 소비 증가(추가 `O(N)` 캐시) | 재계산 발생으로 실행 시간 증가 | 재계산 비용 vs 캐시 유지 비용 비교 |
| 적용 사례 | 웹 API 응답 지연 최소화 | 임베디드·모바일·스트리밍 집계 | 서버리스는 실행시간×메모리(GB-초)로 과금되어 양쪽 동시 통제 필요 |

> 요약: 응답시간 SLA가 우선이면 시간 우선 설계, 메모리 상한이 빡빡하면 공간 우선 설계를 선택하며, 서버리스 환경은 두 값을 함께 통제해야 함.

**리스크·대응 (불릿):**
- 조기 최적화: 프로파일링 없이 직관으로 최적화 시 병목이 아닌 곳을 고쳐 가독성만 저하 → 실제 병목을 프로파일링으로 먼저 확인 (지표: 프로파일링 커버리지)
- 최악 케이스 미검증: 평균 케이스만 검증하면 특정 입력에서 성능이 급락 → 적대적 입력으로 최악 케이스 테스트를 CI에 포함 (지표: 최악 케이스 응답시간 p99)
- 공간 복잡도 방치: 메모이제이션 남용으로 `O(N)` 이상 메모리가 누적 → 캐시 크기 상한·TTL 설정으로 메모리 사용을 통제 (지표: 힙 사용량, OOM 발생 건수)

**도입 후 점검 지표 (불릿):**
- 성능/효율: 최악 케이스 응답시간 p99 목표치 대비 실측 — 부하테스트로 측정
- 품질/운영: 메모리 사용량 상한 대비 실측치, OOM 발생률 — APM 모니터링으로 측정

## Ⅵ. 실무 적용 및 결론

1. 단기: 핵심 로직의 반복·재귀 구조를 분석해 `T(N)`·`S(N)` 등급을 문서화함
2. 중기: 적대적 입력으로 최악 케이스를 CI에 포함해 SLA 위반 여부를 사전 검증함
3. 장기: 데이터 증가 추이를 반영한 용량 계획에 복잡도 분석을 정례화함

- 기술사적 판단: `N`의 향후 증가 규모와 자원 제약(응답시간 SLA vs 메모리 상한) 중 어느 쪽이 지배적인가로 시간-공간 트레이드오프 방향을 결정함
- 기술사 제언: 복잡도 분석은 이론적 도구가 아니라 클라우드 비용(실행시간·할당 메모리)을 직접 좌우하는 엔지니어링 판단 근거로 다뤄야 함
