## 미리 알고가기

- 입력 크기 $n$: 알고리즘 비용을 비교할 때 기준이 되는 데이터 규모임
- 기본 연산: 비교, 대입, 해시 계산 등 반복 횟수를 세는 작업 단위임
- 보조 공간: 입력 데이터 자체를 제외하고 추가로 쓰는 메모리임
- 최악 경우: 가능한 입력 중 비용이 가장 크게 드는 경우임

## Ⅰ. 개요

- **정의/개념**: 시간복잡도는 입력 크기 $n$이 커질 때 기본 연산 수가 얼마나 늘어나는지 나타내는 기준임. 공간복잡도는 추가 메모리가 얼마나 늘어나는지 나타내는 기준임
- **배경/필요성**: 기능이 같아도 입력이 커지면 실행시간이나 메모리 사용량이 먼저 한계에 닿을 수 있음. 따라서 구현 전부터 증가율을 보고 알고리즘을 비교해야 함

## Ⅱ. 특징

- 입력 증가에 따른 비용 변화를 보므로 특정 장비의 실행시간보다 알고리즘 구조 비교에 적합함
- 시간과 공간은 서로 바뀔 수 있어, 캐시나 보조 배열을 쓰면 시간이 줄고 메모리는 늘 수 있음
- 평균 경우만 보면 편향 입력에서의 지연을 놓칠 수 있으므로 최악 경우를 함께 확인해야 함
- 재귀, 큐, 임시 배열 등 숨어 있는 보조 공간까지 봐야 실제 메모리 부담을 알 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 보는 대상 | 기본 연산 수의 증가율 | 추가 메모리 사용량의 증가율 |
| 주요 병목 | 응답 지연, 타임아웃, 처리량 감소 | 메모리 부족, 스와핑, 캐시 효율 저하 |
| 줄이는 방법 | 탐색 범위 축소, 중복 계산 제거, 더 나은 자료구조 사용 | 제자리 처리, 버퍼 재사용, 스트리밍 처리 |
| 대표 판단 | $O(n^2)$ 정렬을 $O(n \log n)$ 정렬로 바꿀지 판단함 | $O(n)$ 보조 배열을 허용할지 판단함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 | 무엇을 $n$으로 볼지 정해야 비교가 흔들리지 않음 |
| 기본 연산 | 비용을 셀 기준 작업이며, 지배적인 반복 연산을 잡아야 함 |
| 증가율 | 입력이 커질 때 비용이 커지는 속도이며, 빅오 표기로 주로 표현함 |
| 분석 조건 | 최선, 평균, 최악 중 어떤 입력을 기준으로 볼지 정하는 조건임 |

```text
+---------+     +-----------+     +---------+
| 입력 n | --> | 기본 연산 | --> | 증가율  |
+---------+     +-----------+     +---------+
      |
      v
+-----------+
| 보조 공간 |
+-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-------------+     +-------------+     +-----------+
| 입력 기준 | --> | 반복 구조 확인 | --> | 지배항 도출 | --> | 복잡도 표기 |
+-----------+     +-------------+     +-------------+     +-----------+
```

1. 입력 크기를 어떤 변수로 볼지 정함
2. 가장 많이 반복되는 기본 연산을 찾음
3. 연산 수와 추가 메모리 사용량을 함수로 표현함
4. 지배항만 남겨 시간복잡도와 공간복잡도를 정리함

## Ⅵ. 실무 적용 및 유의점

1. 대용량 배치나 실시간 API에서는 평균 지연만 보지 말고 최악 입력의 실행시간과 메모리 사용량을 함께 측정해야 함
2. 메모리를 써서 시간을 줄이는 구조를 선택할 때는 최대 입력 크기에서 보조 공간이 허용 범위 안에 있는지 확인해야 함

## Ⅶ. 결론

- 시간복잡도와 공간복잡도는 알고리즘의 확장성을 판단하는 기본 기준이며, 둘을 함께 봐야 실제 병목을 놓치지 않음
