## 미리 알고가기

- 점근 표기: 입력 크기 $n$이 커질 때 증가율만 남겨 복잡도를 표현하는 방법임
- 지배항: 복잡도 함수에서 증가율을 사실상 결정하는 최고차항임
- 보조 공간: 입력 데이터 자체를 제외하고 알고리즘이 추가로 사용하는 메모리임

## Ⅰ. 개요

- **정의/개념**: 시간복잡도는 알고리즘이 입력 크기 $n$ 증가에 따라 기본 연산을 얼마나 더 수행하는지 함수로 나타내는 기준이며, 공간복잡도는 같은 조건에서 추가 메모리를 얼마나 더 요구하는지 나타내는 기준임
- **배경/필요성**: 같은 기능이라도 데이터 규모가 커지면 응답시간과 메모리 소모가 병목으로 바뀌므로, 구현 전에 확장성과 자원 한계를 정량적으로 판단할 기준이 필요함

## Ⅱ. 특징

- 시간복잡도는 실행 속도와 처리량의 한계를, 공간복잡도는 메모리 수용 능력과 동시 처리 규모의 한계를 직접 보여줌
- 복잡도는 하드웨어 세대가 바뀌어도 증가율 자체는 유지되므로 알고리즘 구조 비교에 적합함
- 실제 설계에서는 시간을 줄이기 위해 캐시, 해시, 메모이제이션을 쓰거나 공간을 줄이기 위해 제자리 연산을 택하는 식의 상호 교환 관계가 자주 발생함
- 평균 성능보다 최악 성능 관리가 중요한 서비스에서는 $Worst$ $Case$ 복잡도가 자료구조와 알고리즘 선택의 기준이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 시간복잡도 | 공간복잡도 |
|:---|:---|:---|
| 측정 대상 | 비교, 대입, 탐색, 호출 등 연산 수 | 배열, 스택, 해시, 버퍼 등 추가 메모리 |
| 장애 형태 | 응답 지연, 타임아웃, 처리량 저하 | $OOM$, 스와핑, 캐시 미스 증가 |
| 개선 방향 | 연산 단계 축소, 탐색 범위 축소 | 제자리 처리, 버퍼 축소, 재사용 |
| 대표 판단 예 | $O(n^2)$에서 $O(n \log n)$ 전환 | $O(n)$ 보조 배열을 $O(1)$로 축소 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 크기 $n$ | 데이터 수, 정점 수, 행렬 크기 등 문제 규모를 나타냄 무엇을 $n$으로 둘지 먼저 고정해야 함 |
| 기본 연산 | 비교, 교환, 해시 조회, 재귀 호출 등 비용 계산 단위이며 지배 연산을 잘못 잡으면 분석이 왜곡됨 |
| 보조 저장소 | 임시 배열, 콜 스택, 큐, 캐시 구조이며 입력 외 추가 메모리만 계산함 |
| 분석 시나리오 | $Best$, $Average$, $Worst$ 중 어떤 조건을 볼지 정하고 운영 시스템은 보통 $Worst$ 기준이 우선임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 입력정의 | --> | 연산식별 | --> | 비용계산 | --> | 표기확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **입력정의**: 크기 변수 $n$과 자원 제약 조건을 정함
2. **연산식별**: 가장 자주 반복되거나 병목이 되는 연산과 보조 공간을 찾음
3. **비용계산**: 반복문, 재귀식, 자료구조 사용량을 함수 형태로 정리함
4. **표기확정**: 지배항만 남겨 $O(f(n))$로 단순화해 비교 기준으로 사용함

## Ⅵ. 문제점 및 해결 방안

1. **상수항 무시로 실제 성능을 오판함**: 복잡도는 같아도 캐시 지역성이나 상수 비용 차이로 실행시간이 크게 달라질 수 있음
   - **해결 방안**: 복잡도 분석 뒤에 실제 데이터 크기 구간별 벤치마크를 병행하고 $p95$ 지연시간, $CPU$ 사용률로 검증함
2. **평균 성능만 보고 최악 성능을 놓침**: 평균 $O(1)$ 구조도 충돌이나 편향 입력에서 급격히 느려질 수 있음
   - **해결 방안**: 서비스 중요 구간은 $Worst$ $Case$ 보장 구조로 설계하고 최악 입력에서 응답 상한로 검증함
3. **공간복잡도를 과소평가함**: 재귀 깊이, 큐 크기, 임시 배열이 실제 운영 메모리를 초과할 수 있음
   - **해결 방안**: 보조 공간을 입력 크기별로 산정하고 필요 시 반복문, 스트리밍, 제자리 처리로 전환하고 피크 메모리로 검증함

## Ⅶ. 적용 사례

- 대규모 정렬 배치: $O(n^2)$ 정렬을 $O(n \log n)$ 정렬로 전환해 야간 배치 시간을 단축함, 확인 지표는 총 실행시간과 $CPU$ 점유율임
- 임베디드 제어: 보조 배열을 없앤 제자리 알고리즘으로 제한된 $RAM$ 내에서 동작시킴, 확인 지표는 피크 메모리와 재시작 빈도임
- 캐시 서버: 메모리를 더 써서 반복 계산을 줄이는 메모이제이션을 적용함, 확인 지표는 캐시 적중률과 평균 지연시간임

## Ⅷ. 결론

시간복잡도와 공간복잡도는 알고리즘의 확장성과 운영 가능성을 함께 판단하는 기준이므로, 기술 선택 시 속도와 메모리 중 무엇이 병목인지 먼저 확정하고 그에 맞는 균형점을 잡아야 함.
