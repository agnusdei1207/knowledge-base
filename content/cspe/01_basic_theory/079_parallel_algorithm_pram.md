# 📖 【암기용】 개념 완전 이해

> 목적: PRAM 모델을 처음 보는 사람도 직관적으로 이해하게 만든다.

## 한눈에
- **개요**: 병렬 알고리즘을 설계하고 성능을 분석하기 위해 튜링 머신 대신 사용하는 "이상적인 병렬 컴퓨터 수학 모델"이다. 무한한 프로세서가 하나의 공용 메모리를 지연 없이 공유한다고 가정한다.
- **왜 필요한가**: 실제 멀티코어 환경은 캐시, 통신 지연, 네트워크 구조 등 하드웨어 변수가 너무 많아 알고리즘 자체의 순수 병렬 효율성을 수학적으로 평가하기 어렵기 때문에 필요하다.
- **핵심 직관**: PRAM은 "통신 비용이 0원이고, 무한 명의 요리사가 하나의 거대한 냉장고(공유 메모리)를 동시에 마음대로 쓸 수 있는 꿈의 주방"이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| PRAM (Parallel Random Access Machine) | 병렬 계산을 위한 추상 수학 모델 | "마찰력이 0인 이상적인 물리학 실험실" |
| EREW (Exclusive Read Exclusive Write) | 겹치지 않게 읽고, 겹치지 않게 쓴다 | "냉장고 칸마다 한 번에 한 명만 접근 가능" |
| CREW (Concurrent Read Exclusive Write) | 동시에 읽되, 쓰기는 혼자서만 한다 | "게시판 글은 다 같이 읽지만, 글쓰기는 순서대로" |
| CRCW (Concurrent Read Concurrent Write) | 동시에 읽고, 동시에 쓰는 최강 모델 | "한 화이트보드에 여러 명이 동시에 그리기" |

## 깊이 이해
- **배경·문제의식**: 단일 튜링 머신(RAM 모델)은 알고리즘의 시간 복잡도(Big-O)를 논하는 완벽한 잣대였다. 하지만 병렬 처리 시대가 열리자, 코어가 n개일 때 이론적으로 연산 시간이 얼마나 단축되는지(Work, Span) 계산할 공통 기준(이상적 모델)이 필요해졌다.
- **작동 원리**: 
  - 수많은 프로세서 $P_1, P_2, \dots, P_n$ 이 글로벌 공유 메모리 $M$ 에 연결되어 있다.
  - 모든 프로세서는 동일한 클럭 동기화(Sync) 하에 동시에 1단계씩 연산한다.
  - 읽기/쓰기 충돌을 어떻게 제어할 것인가에 따라 EREW, CREW, CRCW 모델로 세분화된다. 가장 현실적인 모델은 CREW(동시 읽기 허용)이고, 가장 강력하지만 비현실적인 모델은 CRCW다. CRCW에서 동시 쓰기가 발생할 때 누가 승리할지(우선순위, 공통값, 임계) 추가 규칙이 필요하다.
- **비유**: 단일 RAM 모델이 "혼자서 도서관 책을 전부 찾는 시간"을 재는 거라면, PRAM은 "무한 명의 복제 인간이 텔레파시(지연 없는 메모리)를 써서 도서관 책을 찾는 순수 알고리즘 시간"을 잰다.
- **구체 예시**: $N$개 숫자 더하기. 단일 RAM은 $O(N)$. PRAM(프로세서 $N/2$개)에서는 둘씩 짝지어 더하는 토너먼트 트리를 그리면 $\log N$ 단계만에 끝난다. 즉, 병렬 시간 복잡도는 $O(\log N)$이 된다.
- **흔한 오해·주의점**: "PRAM 모델의 $O(\log N)$ 시간이 현실에서도 똑같이 나온다"는 오해다. 실제로는 캐시 일관성(MESI), 메모리 버스 대역폭 병목, 스레드 동기화 오버헤드가 발생해 $O(\log N)$보다 더 걸린다. PRAM은 알고리즘의 "잠재적 최고 한계치"를 보는 잣대일 뿐이다.

## 연결 개념
- (075) 재귀 알고리즘 마스터 정리 — 병렬화 분석(Work-Span 모델)으로 확장 가능
- 암달의 법칙 (Amdahl's Law) — 병렬화로 얻을 수 있는 실제 성능 향상의 한계

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PRAM은 하드웨어 통신 지연(Latency)과 오버헤드를 배제하고, 공유 메모리 환경에서 순수 병렬 알고리즘의 시간(Span)과 일의 양(Work)을 분석하는 추상적 컴퓨팅 모델이다.
> 2. **가치**: 읽기/쓰기 동시성 허용 범위에 따라 EREW, CREW, CRCW로 분류하여, 복잡한 병렬 알고리즘의 효율성을 튜링 머신(단일 RAM)처럼 통일된 기준으로 수학적 증명이 가능하게 한다.
> 3. **판단 포인트**: PRAM 분석은 이론적 한계치를 제공하므로, 실제 멀티코어 환경 구현 시에는 암달의 법칙(순차 실행 병목)과 캐시 일관성 오버헤드를 보정하여 병렬 최적화를 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 알고리즘의 이론적 성능 평가 지표 이해 | PRAM 모델 정의, 메모리 충돌 제어 3종(EREW/CREW/CRCW) | 병렬 컴퓨팅 하드웨어 구조(SMP/NUMA)만 나열하고 알고리즘 수학 모델(PRAM)을 누락 |
| 단일 모델 대비 성능 분석 기법 확립 | Work(총 연산량), Span(임계 경로 길이), Speedup 수식 | 일반 Big-O 복잡도만 쓰고 병렬 분석 지표(Work-Span) 미사용 |

> 요약: 하드웨어 지식(NUMA 등)이 아니라 알고리즘 분석용 "수학적 추상 모델"로서의 PRAM 개념과 3대 동시성 제어 분류를 명확히 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 공통 클럭으로 동기화된 다수의 프로세서가 하나의 무한한 공유 메모리에 접근하여 병렬로 연산을 수행하는 추상적 알고리즘 수학 모델
- 배경: 기존 순차적 튜링 머신(RAM) 모델로는 스레드 간 통신 및 동기화가 존재하는 병렬 알고리즘의 효율성을 객관적으로 비교·분석하기 어려움
- 필요성: 캐시 구조, 네트워크 위상 등 기계 종속적인 하드웨어 변수를 배제하고, 알고리즘 내재적 병렬성(고유 스텝 수)만을 순수하게 정량화하기 위해 필요

---

## Ⅱ. 구조 및 구성요소 (PRAM 메모리 접근 분류)

```text
[동기화 클럭]  -->  프로세서 P_1, P_2, ... P_n (동시 스텝 실행)
                           |      |         |
[통신 지연=0]  <==> (동시 읽기/쓰기 규칙 적용: EREW / CREW / CRCW)
                           |      |         |
[무한 공유 메모리] <== Global Memory (Cell 1, Cell 2, ... Cell M)
```

| 분류 모델 | 읽기 (Read) | 쓰기 (Write) | 특징 및 적용 |
|:---|:---|:---|:---|
| EREW (Exclusive R/W) | 상호 배제 | 상호 배제 | 가장 엄격하고 현실적인 모델 (동시 접근 금지) |
| CREW (Concurrent R, Ex. W)| 동시 허용 | 상호 배제 | 실무와 유사(읽기는 다중, 쓰기는 락 제어) |
| CRCW (Concurrent R/W) | 동시 허용 | 동시 허용 | 가장 강력한 이론 모델 (쓰기 충돌 해결 규칙 필요) |

> 요약: PRAM은 동시 읽기/쓰기 허용 수준에 따라 표현력과 알고리즘 구현의 복잡도가 달라지며, CRCW는 쓰기 충돌 시 우선순위, 임의 선택, 공통값 규칙 등으로 해소한다.

---

## Ⅲ. 동작원리 및 흐름도 (성능 분석 지표: Work-Span)

```text
알고리즘 연산 종속성 그래프(DAG) 구성 -> 정점 전체 합(Work) 계산
-> 가장 긴 의존성 경로(Span) 산출 -> 가용 프로세서(P) 기반 최종 시간 T(P) 예측
```

- 1단계 [Work 계산]: 프로세서가 1개일 때 알고리즘을 완료하는 데 필요한 총 순차 연산량($W$ 또는 $T_1$) 산출
- 2단계 [Span 계산]: 무한대의 프로세서가 주어졌을 때 완료할 수 있는 최단 시간, 즉 임계 경로 길이($S$ 또는 $T_\infty$) 산출
- 3단계 [Speedup 산출]: 병렬화로 얻는 속도 향상 비율 $Sp = \frac{T_1}{T_p}$ 계산 (이상적 목표: $Sp \approx p$)
- 4단계 [Brent의 정리 적용]: $P$개의 프로세서가 있을 때의 실제 수행 시간 $T_p \le \frac{W - S}{P} + S$ 한계선 증명

> 요약: 병렬 알고리즘의 우수성은 총 작업량(Work)을 늘리지 않으면서, 임계 경로(Span)를 획기적으로 줄이는 것에 있다(예: N개 덧셈의 Span은 $O(\log N)$).

---

## Ⅳ. 특징
- [추상적 한계]: PRAM은 메모리 접근 시간과 프로세서 동기화(Sync) 오버헤드가 0이라고 가정하므로, 실측 성능이 아닌 이론적 상한선(Upper Bound)만 제시
- [CRCW의 강력함]: CRCW 모델은 N개의 수 중 최댓값을 찾는 문제를 이상적으로 $O(1)$ 스텝에 해결 가능함을 증명하여 병렬 알고리즘 연구의 극단을 보여줌
- [시뮬레이션 가능성]: 물리적으로 강력한 CRCW 모델에서 설계된 알고리즘도 $O(\log P)$ 시간의 정렬(Sorting) 오버헤드를 감수하면 현실적인 EREW 머신에서 시뮬레이션 구현 가능

> 요약: PRAM은 마찰력 없는 물리 실험실처럼, 하드웨어 제약을 벗어나 알고리즘 자체의 극한 병렬 가능성을 평가하는 기준점이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단일 RAM 모델 | PRAM 모델 | 적용 실무 아키텍처 |
|:---|:---|:---|:---|
| 프로세서 수 | 1개 (순차) | N개 (무한 병렬) | 멀티 코어 (CPU/GPU) |
| 메모리 제약 | 로컬 메모리 | 지연 없는 글로벌 공유 메모리 | SMP (대칭형 다중 프로세서) |
| 분석 지표 | 시간 $O(N)$ / 공간 $O(1)$ | Work / Span / Speedup | GPGPU CUDA 스레드 스케줄링 |

> 요약: 단일 RAM이 알고리즘 기초 수업의 잣대라면, PRAM은 대규모 데이터 병렬 처리(Hadoop, GPU 커널) 알고리즘 논문의 기본 평가 잣대다.

**리스크·대응:**
- [암달의 법칙 한계]: PRAM에서 Span($T_\infty$)을 아무리 줄여도 알고리즘 내 순차적 부분(S)이 5% 남으면 최대 성능 향상이 20배로 고정됨 → 순차 병목 로직(Sequential Bottleneck) 재설계 강제 (지표: 최대 Speedup 임계점 도달 여부)
- [비현실적 메모리 지연]: PRAM의 지연 '0' 가정이 현실의 캐시 미스/NUMA 지연과 충돌하여 병렬 효율 급감 → BSP(Bulk Synchronous Parallel) 모델이나 메모리 통신 비용을 반영한 LogP 모델로 설계 보완

**도입 후 점검 지표:**
- 성능/효율: 병렬 효율성(Efficiency = $Sp/P$) — 목표치 0.7 이상 방어 모니터링
- 품질/운영: 스레드 확장성에 따른 실제 오버헤드 커브 추적 — 프로세서 증설 대비 응답시간 단축률 계측

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. [GPU 커널 알고리즘 설계]: CUDA 프로그래밍 전, 알고리즘을 CREW PRAM 모델로 추상화하여 각 스레드의 읽기 충돌과 쓰기 병목 구간(Span)을 수학적으로 사전 진단 후 Shared Memory 활용 설계
2. [병렬 분할 정복 도입]: 대용량 배열 정렬 시 Work-Span 분석을 적용한 병렬 병합 정렬(Parallel Merge Sort)을 구현하여, 이론적 최단 $O(\log^3 N)$ Span 목표에 맞춘 Fork-Join 스레드풀 구축
3. [현실적 오버헤드 보정]: PRAM 분석으로 검증된 이상적 알고리즘을 실제 클러스터에 배포할 때, 통신 오버헤드가 반영된 MapReduce(순차 장벽 동기화) 구조로 매핑하여 튜닝

**결론:**
- 기술사 판단: 실무에서 멀티 스레드 코드를 무작정 짜기 전에, PRAM 모델의 Work-Span 분석을 통해 "이 알고리즘이 병렬화로 얻을 수 있는 이론적 이득의 한계치"가 하드웨어 증설 비용을 상회하는지 먼저 수학적으로 판증해야 한다.
- 향후 방향: 전통적 PRAM을 넘어 딥러닝 텐서 코어, HBM 메모리의 비대칭적 지연율을 수학적으로 반영한 최신 혼합 병렬 연산 모델들(예: Multi-BSP)로 분석 기준이 진화하고 있다.
