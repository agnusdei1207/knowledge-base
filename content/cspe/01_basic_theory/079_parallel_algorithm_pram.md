# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **병렬 컴퓨팅**에서 여러 프로세서가 하나의 공유 메모리에 동시에 접근할 때의 규칙을 정의해 병렬 알고리즘을 수학적으로 분석할 수 있게 만든 이론 모델이 PRAM(Parallel Random Access Machine)이며, 프로세서를 늘려도 속도가 그만큼 비례해 늘지 않는 한계를 정량화한 것이 암달의 법칙과 구스타프슨의 법칙이다.
- **왜 필요한가**: CPU 코어가 1개에서 8개로 늘었다고 처리 속도가 그대로 8배가 되지는 않는다. 여러 코어가 같은 메모리 주소를 동시에 읽고 쓰려 할 때 순서를 정해야 하고(메모리 접근 충돌), 알고리즘 안에는 아무리 코어를 늘려도 나눌 수 없는 순차 작업이 반드시 남아 있기 때문이다. PRAM은 전자(메모리 충돌)를, 암달/구스타프슨 법칙은 후자(순차 병목)를 수식으로 다룬다.
- **핵심 직관**: PRAM의 핵심은 "여러 프로세서가 동시에 읽는 것(Concurrent Read)"과 "동시에 쓰는 것(Concurrent Write)"을 허용할지, 아니면 한 번에 하나씩만 접근하게 막을지(Exclusive)를 정하는 4가지 조합 규칙이고, 암달의 법칙의 핵심은 "전체 작업 중 병렬화가 불가능한 순차 비율이 성능 향상의 상한을 결정한다"는 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 병렬 컴퓨팅 | 여러 프로세서가 작업을 나눠 동시에 처리하는 방식 — PRAM이 속한 상위 개념 | 한 사람이 할 일을 여러 명이 나눠 하는 것 |
| 공유 메모리 | 여러 프로세서가 동일한 메모리 주소 공간을 함께 읽고 쓰는 구조 | 여러 명이 같은 칠판에 동시에 쓰는 것 |
| PRAM (Parallel Random Access Machine) | 무한한 수의 프로세서가 하나의 공유 메모리에 동시 접근할 수 있다고 가정한 이상화된 병렬 계산 모델 | 병렬 알고리즘의 성능을 재는 실험실용 모형 |
| EREW (Exclusive Read, Exclusive Write) | 읽기도 쓰기도 한 번에 프로세서 하나만 접근 허용 | 좁은 문을 한 사람씩만 드나드는 것 |
| CREW (Concurrent Read, Exclusive Write) | 읽기는 여러 프로세서가 동시에, 쓰기는 한 번에 하나만 허용 | 여러 명이 동시에 칠판을 보되, 쓸 때는 한 명씩 순서대로 |
| CRCW (Concurrent Read, Concurrent Write) | 읽기와 쓰기 모두 동시 허용, 단 쓰기 충돌을 해결할 규칙이 별도로 필요 | 여러 명이 동시에 칠판에 쓰되, 충돌 시 규칙으로 승자를 정함 |
| 임계 구역 (Critical Section) | 동시에 여러 프로세서가 접근하면 데이터가 깨지는 공유 자원 구간, 락으로 보호해야 함 | 화장실 한 칸 — 한 번에 한 사람만 |
| 암달의 법칙 (Amdahl's Law) | 병렬화 불가능한 순차 작업 비율이 전체 성능 향상의 상한을 정한다는 공식 | 아무리 인부를 늘려도 자물쇠 하나 따는 시간은 줄지 않는다 |
| 구스타프슨의 법칙 (Gustafson's Law) | 코어가 늘어나면 처리할 데이터 크기도 함께 키운다는 전제로 성능을 계산하는 공식 | 인부가 늘면 그만큼 더 큰 집을 짓는다 |

## 깊이 이해

### PRAM의 4가지 모델이 존재하는 이유 — 메모리 접근 충돌을 어떻게 다루나
- 여러 프로세서가 같은 메모리 주소를 동시에 "읽기"만 하면 값이 바뀌지 않으므로 문제가 없다. 하지만 동시에 "쓰기"를 하면 어느 값이 최종적으로 남을지 정의되지 않는 경쟁 상태(Race Condition)가 발생한다.
- 그래서 읽기·쓰기 각각을 동시 허용(Concurrent)할지 배타적으로 하나씩만(Exclusive) 허용할지의 2×2 조합으로 EREW, CREW, ERCW, CRCW 4가지 모델이 나온다. 이 중 읽기는 막고 쓰기만 동시 허용하는 ERCW는 논리적으로 의미가 약해 실제로는 거의 쓰이지 않고, EREW·CREW·CRCW 세 가지가 실질적으로 쓰인다.
- CREW가 가장 널리 쓰이는 이유는 실무의 읽기·쓰기 비율과 맞기 때문이다: 데이터베이스 조회처럼 읽기는 빈번하고 동시에 일어나도 안전하지만, 쓰기(갱신)는 정합성을 위해 순서를 정해야 하는 경우가 많다.

### CRCW의 쓰기 충돌 해결 규칙 — 프로세서 3개가 동시에 쓸 때
- 프로세서 P1, P2, P3가 동시에 같은 메모리 주소 M에 각각 5, 7, 3을 쓰려고 한다고 하자.
- **Common(공통)**: 모든 프로세서가 쓰려는 값이 동일할 때만 쓰기를 허용한다. 이 경우 값이 5·7·3으로 서로 다르므로 쓰기가 거부되거나 오류로 처리된다.
- **Arbitrary(임의)**: 충돌한 프로세서 중 하나를 무작위로 골라 그 값만 기록한다. 예를 들어 P2가 뽑히면 M에는 7이 저장된다.
- **Priority(우선순위)**: 미리 정해둔 프로세서 번호 순서(예: 번호가 낮은 프로세서 우선)에 따라 승자를 정한다. P1이 우선순위가 가장 높다면 M에는 5가 저장된다.

### 암달의 법칙 — 숫자로 보는 병렬화의 한계
- 공식: S = 1 / ((1-P) + P/N). 여기서 P는 전체 작업 중 병렬화 가능한 비율, N은 프로세서(코어) 수, S는 속도 향상 배수다.
- 예: 작업의 90%가 병렬화 가능하다면(P=0.9), 코어 10개(N=10)일 때 S = 1/(0.1 + 0.9/10) = 1/0.19 ≈ 5.26배. 코어를 100개로 늘려도 S = 1/(0.1 + 0.009) ≈ 9.17배로, 10배에 가까워지긴 하지만 넘지는 못한다.
- 코어 수를 무한대로 보내면(N→∞) S는 1/(1-P)로 수렴한다. P=0.9면 상한은 1/0.1=10배다. 즉 순차 비율이 단 10%만 있어도, 아무리 코어를 늘려도 10배를 절대 넘을 수 없다.
- 순차 비율이 더 크면 한계는 더 낮아진다. P=0.5(절반만 병렬화 가능)면 코어를 무한히 늘려도 최대 2배 향상에 그친다.

### 구스타프슨의 법칙 — 문제 크기를 함께 키우면 그림이 달라진다
- 공식: S = (1-P) + N·P. 암달의 법칙과 달리 "코어가 늘면 처리할 데이터 양도 늘린다"는 전제를 깐다.
- 같은 P=0.9, N=10 조건에서 S = 0.1 + 9 = 9.1배로, 암달의 법칙이 준 5.26배보다 훨씬 높다. 코어 수에 거의 비례해 성능이 느는 것처럼 보인다.
- 두 법칙의 차이는 가정의 차이일 뿐 모순이 아니다: 암달은 "정해진 크기의 문제를 얼마나 빨리 끝내는가"를 묻고, 구스타프슨은 "정해진 시간 안에 얼마나 큰 문제를 처리할 수 있는가"를 묻는다. 빅데이터 분석처럼 데이터가 늘어날수록 함께 처리량을 키우는 상황에는 구스타프슨의 관점이 더 들어맞는다.

### 비유
- 100장의 벽돌을 나르는 작업을 생각하면, 자물쇠로 잠긴 창고 문을 여는 일(순차 작업)은 인부가 1명이든 100명이든 걸리는 시간이 똑같다. 문을 연 뒤 벽돌을 나르는 일(병렬 작업)만 인부 수에 비례해 빨라진다. 이 창고 문 여는 시간이 암달의 법칙이 말하는 "순차 병목"이다.

## 연결 개념
- 공유 메모리 아키텍처(SMP) — 모든 CPU 코어가 동일한 물리 메모리 주소 공간을 공유하는 구조, PRAM이 이론적으로 모델링하는 대상
- 메시지 패싱(MPI) — 메모리를 공유하지 않고 네트워크 통신으로 데이터를 주고받는 분산 모델, PRAM의 공유 메모리 전제와 대비됨
- 임계 구역 / 뮤텍스(Mutex) — 동시 쓰기 충돌을 막기 위해 실제 시스템에서 사용하는 락 메커니즘

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PRAM의 4대 메모리 접근 통제 스키마(EREW, CREW 등) 메커니즘을 명시하고, 병렬 알고리즘 성능 평가 모델(Amdahl vs Gustafson)의 수학적 극한 한계 증명 및 극복 튜닝 아키텍처를 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PRAM은 공유 메모리 병렬 컴퓨팅 환경에서 다중 프로세서의 동시 읽기/쓰기(Concurrent/Exclusive) 충돌 통제 제약을 규정한 락(Lock) 알고리즘 설계 추상 모델이다.
> 2. **가치**: 알고리즘 내 임계 구역(Critical Section)의 동기화 오버헤드를 모델링하고, 암달의 법칙(Amdahl)을 통해 하드웨어 증설 대비 병렬화 효율이 박살 나는 한계 지점을 사전 도출 통제하게 해준다.
> 3. **판단 포인트**: 멀티코어 환경 설계 시 병렬화 불가능한 순차 실행 병목(Amdahl 한계) 직면 시 맹목적 코어 증설을 멈추고, Gustafson 법칙에 기반하여 데이터 볼륨 단위 워크로드를 파티셔닝(스케일 아웃) 방어 튜닝해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 메모리 병렬 알고리즘 상호배제 락 통제 모델링 | PRAM 4대 분류 체계 (EREW, CREW, ERCW, CRCW) 기재 맵핑 | 알고리즘 통제 모델 뼈대 누락 후 단순 코어 하드웨어 장비 스펙 나열 서술 |
| 동시 쓰기(CW) 덮어쓰기 충돌 회피 룰 체득 | CRCW 락프리 쓰기 충돌 방어 해결법 (Common, Arbitrary, Priority) | 단순히 "동시 쓰기는 충돌 나서 안 된다" 수준의 비전문가적 단답 서술 |
| 병렬 성능 극한 한계 수식(Scale) 평가 법칙 대조 | Amdahl 암달 법칙(순차 병목) vs Gustafson 구스타프슨(데이터 스케일 방어) 역수 증명 수식 대조 | 두 상반된 법칙의 극한(Limit) 가정을 반대로 혼동 기재 혹은 증명 수식 누락 |

> 요약: PRAM의 메모리 접근 통제 매트릭스를 기반으로 병렬 동기화 파이프라인을 짜고, 그 알고리즘 로직이 처박힐 성능 장벽 상한선을 Amdahl과 Gustafson 수식으로 정량 계산 돌파 방어하는 뼈대다.

## Ⅰ. 개요 및 필요성

- 정의: 무제한 프로세서 노드가 단일 거대 공유 메모리(Shared Memory)를 글로벌 동기화 클럭 시계에 맞춰 접근(Access) 제어하는 병렬 알고리즘 추상화 설계 뼈대 모델
- 배경: 물리적 멀티코어 집적 및 GPU 증설 장착에도 불구, 상호 배제(Mutual Exclusion) 락(Lock) 스핀 대기로 인한 병목 탓에 선형적 속도 향상(Linear Speed-up) 실패 셧다운 빈발 도래
- 필요성: 알고리즘 로직 내부의 메모리 읽기/쓰기 접근(Concurrent Access) 제약 조합을 규격화(CREW 등) 파악하여, 병렬화 투입 TCO 성능 상한선을 사전 수학적 증명 및 락프리 통제할 체계 필수

## Ⅱ. 구조 및 구성요소 (PRAM 메모리 접근 락 제어 매트릭스)

```text
공유 주소 [ M ] <--- 동시/배타 상호배제 락 제어망 적용 <--- 쿼리 프로세서 P1, P2 ... Pn
[ PRAM 락 팩터 파라미터 : Read (Concurrent 다발적 / Exclusive 단독) X Write (Concurrent 다발적 / Exclusive 단독) ]
```

| 접근 통제 아키텍처 모델 | 메모리 읽기(Read) 권한 | 메모리 쓰기(Write) 권한 | 동작 특징 및 상호배제 충돌 방어 기전 |
|:---|:---|:---|:---|
| **EREW** (배타/배타) | Exclusive (단독 락) | Exclusive (단독 락) | 가장 갑갑한 제약, 동시 접근 원천 금지로 정합성은 완벽하나 락 큐(Queue) 대기 지연 폭주 |
| **CREW** (동시/배타) | Concurrent (무제한) | Exclusive (단독 락) | 가장 범용적 표준 대안, 읽기는 다발 허용하되 쓰기 덮어쓰기만 임계 구역 세마포어 통제 방어 |
| **ERCW** (배타/동시) | Exclusive (단독 락) | Concurrent (무제한) | 읽기는 막는데 쓰기는 허용하는 논리 모순, 실제 시스템 설계 시 전면 폐기 맵핑 |
| **CRCW** (동시/동시) | Concurrent (무제한) | Concurrent (무제한) | 병렬 한계 돌파형. 단, 동시 쓰기 정합성 박살을 막기 위한 강제 하드웨어 쓰기 중재 룰 적용 락인 필수 |

> 요약: 실제 상용 RDBMS 동시성 제어 MVCC 베이스가 되는 CREW 모델을 뼈대로, Read 파이프라인 처리량(Throughput)은 무제한 극대화하되 Write 동시 락 경합 충돌은 완벽 고립 차단하는 아키텍처로 수렴한다.

## Ⅲ. 동작원리 및 CRCW 무차별 쓰기 충돌 해결 흐름도

```text
[CRCW 동시 쓰기 Race Condition 폭주] -> CPU 노드 3개가 동일 주소 'M'에 동시 Write 인터럽트 
-> 하드웨어 중재 칩셋 개입 -> [ 충돌 해결 정책(Resolution Rule) 컷오버 적용 방어 ] -> 오직 한 놈의 값만 Write 레지스터 성공
```

| 쓰기 충돌 제어 방어 룰 | 동시 쓰기(CW) 폭주 시 데이터 정합성 확정 메커니즘 통제 | 실무 알고리즘 방어 맵핑 예시 |
|:---:|:---|:---|
| **Common (공통 강제)** | 쓰기를 들이미는 모든 프로세서 노드의 '수치 값'이 100% 동일할 때만 기록 승인, 불일치 시 버려짐(Error) | 분산 파드 헬스체크(All-OK) 동기화 플래그 단일 취합 업데이트 락인 |
| **Arbitrary (임의 랜덤)** | 충돌 시도 프로세서 중 랜덤 난수로 한 놈을 승리자로 선정 격상시켜 무조건 덮어쓰기 기록 컷오버 | 유전 알고리즘 몬테카를로 난수 탐색 중 최초 해답 발견 즉시 스핀락 뚫고 보고 |
| **Priority (우선순위 PID)** | 사전에 부여 인덱싱된 PID 넘버가 가장 낮거나/높은 VIP 우선순위 코어의 값만 배타적 기록 인정 방어 | 클러스터 마스터-슬레이브 복제 룰 덮어쓰기, 메인 0번 코어 강제 기록 권한 |

> 요약: CRCW 파이프라인은 병렬 대기 큐를 날려버려 가장 빠른 연산 능력을 뿜지만, 위 3가지 락 프리(Lock-free) 하드웨어 중재 룰을 꽂지 않으면 메모리 주소 정합성이 1 밀리초 만에 즉각 붕괴된다.

## Ⅳ. 병렬 성능 통제 극한 법칙 (Amdahl vs Gustafson 딜레마)

| 한계 증명 비교 척도 축 | 암달의 법칙 (Amdahl's Law 절망 한계) | 구스타프슨의 법칙 (Gustafson's Law 희망 돌파) | 시스템 아키텍처 튜닝 판단 기준 |
|:---|:---|:---|:---|
| 핵심 가정(직관 시점) | "데이터 크기 워크로드는 고정 불변, CPU 코어 머릿수만 늘린다" | "코어가 팽창하면 사람들은 더 거대한 빅데이터 볼륨을 때려 박는다" | 데이터 파이프라인 스케일 (Scale-up 장비 vs out 볼륨) 방향성 |
| 성능 팽창 한계 수식 | $S = \frac{1}{(1-P) + P/N}$<br>($P$: 연산 병렬 비율, $N$: 코어 증설수) | $S = (1-P) + N \cdot P$<br>($P$: 병렬 런타임 비율, $N$: 팽창 코어수) | $N \rightarrow \infty$ 극한 발산 시의 시스템 벤치 성능 상한 도달률 |
| 극한 수렴 한계 교훈 | 장비 코어($N$)를 무한 팽창해도, 결국 고립된 직렬 순차 비율($1-P$) 병목 역수에 멱살 잡혀 성능 정체 박살 | 입력 데이터 볼륨이 거대해질수록 병렬 분산 튜닝 비율이 압도하여 성능 그래프가 선형 우상향 돌파 방어 | 빅데이터 Hadoop/Spark 분산 파티셔닝 프레임워크 컷오버 타당성 |

> 요약: 암달 공식은 인프라 장비만 무지성 증설 시 직렬화 병목이 멱살을 잡는 셧다운 경고를 날리고, 구스타프슨은 '데이터 셔플 파티셔닝 스케일 아웃'을 통한 병렬성 극대화 락인 방안을 수식 증명한다.

## Ⅴ. 심화 아키텍처 리스크 및 동기화 병목 튜닝 지표

| 튜닝 장애 리스크 종류 | 발생 근본 원인 (병렬화 방해 병목 팩터) | 아키텍처 튜닝 대응 컷오버 통제 방안 | 성능 확인 모니터링 수치 지표 |
|:---|:---|:---|:---|
| 상호배제 락(Lock) 스레드 경합 폭주 | CREW 구현 사수를 위해 공유 자원에 맹목적 Mutex 락을 걸며 수천 개 코어가 스핀락(Spinlock) 무한 점유 대기 셧다운 | Lock-Free / Wait-Free 비동기 큐 자료구조(CAS 연산 기반) 도입 및 스레드 로컬 임시 메모리 파티셔닝(TLS) 튜닝 우회 | CPU 캐시 라인 L2 플러시(Flush) 패널티 카운트 급증율 |
| 물리적 통신 비용(Communication) 지연 한계 | 장착 코어 초과 증가 시 메인보드 공유버스(Bus) 트래픽 병목으로 코어 연산 시간보다 데이터 픽업 전송 I/O 대기시간이 역전 | 연산과 전송 스레드를 비동기 분리(Overlapping) 은닉하고 캐시 친화적 NUMA(Non-Uniform) 핀셋 메모리 할당 타협 | 코어 간 L3 캐시 미스 스파이크율 및 NUMA QPI 인터커넥트 병목 대기율 |

> 요약: 칠판 위 이상적인 PRAM 락프리 공식을 실제 x86 리눅스 칩셋에 무작정 배포하면 버스 I/O 병목과 스핀락 지연으로 암달 절망 수식보다 더 처참한 성능 하락 패널티가 터지므로, NUMA 인지 튜닝이 필수 방패다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 병렬 쿼리 플랜 통제 방어: 데이터웨어하우스(DW) 대용량 스캔 집계 플랜 시 CREW (동시 읽기, 단독 배타 쓰기) 모델을 파이프라인에 강제 락인하여, 다발적 Read 스캔 프로세서는 락 대기 없이 무제한 스케일 아웃하고 Write 트랜잭션 롤백은 직렬화 버퍼 큐로 완벽 격리 통제
2. Spark RDD 데이터 파티셔닝 우회 타협: 하둡 분산 환경 셔플링 시 암달의 법칙 룰에 따른 리듀서(Reducer) 리소스 병목 지연(Straggler)을 방어하기 위해, 데이터를 워커 노드별로 독립 해시 파티셔닝(Shared-Nothing 아키텍처)으로 찢어 EREW 형태의 의도적 상호 배제 타협 처리율 튜닝 유도
3. GPU 쿠다(CUDA) 병렬 아키텍처 선별 투입: 딥러닝 텐서 행렬 곱 연산 등 순차 작업 비율(1-P)이 전체의 1% 미만인 CRCW 특화 은닉 로직은 구스타프슨 법칙을 맹신 근거로 GPU 수천 코어 스케일 아웃 장비에 아낌없이 쏟아부어 선형적 시간 단축 인프라 TCO(총소유비용) 최적화 증명 타결

**결론 (2줄):**
- 기술사 판단: 병렬 알고리즘 설계 최적화는 단순히 CPU 코어를 무지성 꽂는 장비 폭력이 아니라, 순차 처리 비율 병목(Amdahl 한계선)을 핀셋 도려내고 락 프리(Lock-free) CAS 자료구조로 쓰기 충돌을 우회하는 아키텍처 정밀 타격이다.
- 향후 방향: 전통적 SMP 공유 메모리 버스 트래픽 제약을 아득히 넘어, 메시지 패싱(MPI) 기반의 분산 비동기 맵리듀스 병렬화 및 HBM(광대역 메모리)이 다이렉트 결합된 GPU 텐서 아키텍처로 PRAM 통신 딜레이 한계가 급속히 타파 파괴되고 있다.
