# 📖 【암기용】 개념 완전 이해

> 목적: 병렬 알고리즘과 PRAM 모델을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: PRAM은 여러 프로세서가 공유 메모리에 동시에 접근한다고 가정해 병렬 알고리즘의 시간복잡도를 분석하는 추상 모델임
- **왜 필요한가**: 멀티코어, GPU, 분산 처리에서는 한 코어 기준 알고리즘만으로 처리시간을 설명하기 어렵다. 병렬화 가능성과 병목을 이론적으로 분리해 판단해야 함.
- **핵심 직관**: 일을 여러 사람이 나눠도 같은 문서를 동시에 고치면 충돌이 생긴다. PRAM은 읽기·쓰기 충돌 규칙을 정해 병렬 알고리즘의 한계를 분석함.

## 깊이 이해
- **배경·문제의식**: 순차 알고리즘의 O(n) 작업도 n개 프로세서가 있으면 O(1)에 가까워질 수 있지만, 통신·동기화·메모리 충돌이 이를 제한함. PRAM은 이런 하드웨어 세부를 제거하고 병렬성 자체를 분석함.
- **작동 원리**: PRAM은 동기식 단계마다 각 프로세서가 읽기, 계산, 쓰기를 수행한다고 가정함. EREW, CREW, CRCW는 동시 읽기와 동시 쓰기 허용 여부로 나뉨.
- **비유**: 여러 직원이 같은 스프레드시트를 읽고 계산한 뒤 결과 칸에 쓰는 규칙을 정한 것과 같다. 동시에 쓰는 규칙이 없으면 마지막 값이 무엇인지 알 수 없음.
- **구체 예시**: n개 수의 합은 pairwise reduction으로 n개 프로세서에서 O(log n) 단계에 계산 가능하며 총 작업량은 O(n)임.
- **흔한 오해·주의점**: 프로세서 수를 늘리면 무조건 처리시간이 줄어드는 것은 아니다. Amdahl 법칙에 따라 순차 구간 10%가 남으면 최대 speedup은 10배로 제한됨.

## 연결 개념
- Amdahl/Gustafson 법칙 — 병렬화 효과의 상한과 규모 확장 효과
- GPU 병렬 처리 — SIMT, warp, shared memory 충돌과 연결
- MapReduce — 데이터 병렬 처리의 실무 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PRAM(Parallel Random Access Machine)은 p개 프로세서가 공유 메모리를 동기식으로 접근한다고 가정하는 병렬 알고리즘 분석 모델임.
> 2. **가치**: 병렬 시간 T_p, 작업량 W, speedup, processor efficiency를 계산해 병렬화 가능성과 병목을 분리함.
> 3. **판단 포인트**: EREW/CREW/CRCW 접근 규칙, work-depth 모델, 동기화 비용, 메모리 충돌을 함께 제시해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 여러 프로세서가 공유 메모리에 동기식으로 접근한다고 가정하는 병렬 알고리즘 분석 모델
- 배경: 멀티코어·GPU 환경에서는 프로세서 수, 동기화, 메모리 충돌이 실행시간을 좌우함
- 필요성: 하드웨어 세부를 단순화해 알고리즘의 병렬 깊이와 작업량을 비교하는 기준을 제공해야 함

---

## Ⅱ. 구조 및 구성요소

```text
입력 데이터 -> p개 프로세서 -> 공유 메모리 -> 동기화 단계 -> 병렬 결과
                 / EREW
                 / CREW
                 / CRCW
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 프로세서 P1..Pp | 동일 단계에서 읽기·계산·쓰기 수행 | p 값에 따라 T_p 변화 |
| 공유 메모리 | 모든 프로세서가 접근하는 데이터 공간 | 동시 접근 규칙 필요 |
| 접근 모델 | 읽기·쓰기 충돌 허용 범위 결정 | EREW, CREW, CRCW |
| 동기화 단계 | 모든 프로세서가 라운드 단위 진행 | barrier 비용은 실제 구현에서 별도 고려 |

> 요약: PRAM은 프로세서, 공유 메모리, 접근 규칙, 동기화 단계를 통해 병렬 알고리즘의 이론 실행시간을 분석함.

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 분할 -> 프로세서 배정 -> 병렬 읽기/계산 -> 충돌 규칙 적용 -> 병합/동기화 -> 결과 산출
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력을 독립 작업으로 분할 | 작업량 W=O(n) 등 명시 |
| 2 | p개 프로세서에 작업 배정 | 부하 불균형률 측정 |
| 3 | 병렬 계산 및 메모리 접근 | EREW/CREW/CRCW 충돌 규칙 준수 |
| 4 | reduction 또는 prefix 병합 | 병렬 시간 T_p, depth O(log n) 산정 |

> 요약: 병렬 알고리즘은 분할, 배정, 동시 계산, 충돌 처리, 병합 순서로 동작하며 T_p와 W로 평가함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 병렬 시간과 작업량을 하드웨어와 분리해 분석 | T_p, W, speedup=S=T_1/T_p |
| 한계 | 캐시, NUMA, 네트워크, GPU warp 비용은 단순화 | 실제 구현은 프로파일링 필요 |
| 비교 대상 | 순차 RAM은 1개 프로세서 기준 | PRAM은 p개 프로세서와 접근 충돌 기준 |
| 대표 연산 | parallel reduction, prefix sum, sorting network | reduction depth O(log n) |

> 요약: PRAM은 병렬성의 이론 상한을 보여주며 실제 시스템에서는 메모리 계층과 동기화 비용을 추가 검증해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 순차 RAM, 단일 실행 흐름 | p개 프로세서 공유 메모리 | 데이터 독립성이 높으면 병렬 모델 적용 |
| 비용/성능 | T_1 기준 분석 | T_p, W, speedup, efficiency | efficiency 60% 이상 목표 설정 |
| 운영/위험 | 구현 후 측정 중심 | 병렬 깊이 사전 분석 | 동기화·메모리 충돌이 많은 문제는 재설계 |

> 요약: PRAM 분석은 병렬화 전 작업량과 깊이를 계산해 구현 가능성과 병목을 사전에 판단하는 데 적합함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 동기화 병목 | barrier 빈도 증가 | chunk 크기 조정, lock-free 구조 | barrier 대기시간, p95 task time |
| 메모리 충돌 | 동일 주소 동시 쓰기 | reduction tree, atomic 최소화 | atomic retry 수, cache miss |
| 부하 불균형 | 데이터 분포 편차 | work stealing, dynamic scheduling | CPU/GPU utilization 편차 |

> 요약: 병렬 알고리즘 리스크는 동기화, 메모리 충돌, 부하 불균형이며 프로파일링 지표로 확인해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 병렬 시간 | T_p와 depth O(log n) 등 명시 | 이론 분석, benchmark |
| 프로세서 효율 | efficiency=S/p 60% 이상 | p별 speedup 측정 |
| 메모리 접근 | cache miss, atomic retry 제한 | perf, GPU profiler, APM |

> 요약: PRAM 기반 설계는 이론 시간, 프로세서 효율, 메모리 접근 지표를 함께 점검해야 함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 분석 단계: 문제를 work W와 depth D로 분해하고 reduction, prefix sum, partition 같은 병렬 패턴을 식별함.
2. 구현 단계: CPU는 OpenMP/TBB, GPU는 CUDA block/thread 구조를 적용하고 atomic 연산 수와 shared memory 충돌을 제한함.
3. 검증 단계: p=1,2,4,8,16별 speedup, efficiency, cache miss, barrier 대기시간을 측정해 병렬화 구간을 조정함.

**결론 (2줄):**
- 기술사 판단: 데이터 병렬성이 높고 동기화가 적으면 PRAM 기반 병렬화, 순차 의존성이 높으면 알고리즘 재구성 또는 파이프라인 병렬을 선택함.
- 향후 방향: PRAM 분석은 GPU, NUMA, 분산 런타임의 프로파일링 지표와 결합해 병렬 알고리즘 설계 기준으로 활용됨.
