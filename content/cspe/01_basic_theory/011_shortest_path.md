# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 최단 경로 탐색은 **가중치 그래프**에서 두 정점 사이의 간선 가중치 합이 최소가 되는 경로를 찾는 그래프 알고리즘으로, 모든 간선을 "거리 1"로 취급하는 BFS(010)를 실제 비용(거리·시간·요금)이 다른 간선에 대응하도록 확장한 것이다.
- **왜 필요한가**: 내비게이션, 네트워크 라우팅(OSPF·BGP), 물류 배송은 모두 "노드 개수가 적은 길"이 아니라 "총 비용이 적게 드는 길"을 찾아야 한다. 도로마다 거리·통행료·소요 시간이 다르므로 단순히 몇 정거장을 거치는지만 세는 BFS로는 답이 틀린다.
- **핵심 직관**: "지금까지 알아낸 최단 거리보다, 이 정점을 거쳐 가는 게 더 짧은가?"를 모든 간선에 대해 계속 확인하며 거리표를 갱신해 나간다.

## 핵심 용어 정리
| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 가중치 그래프 | 간선마다 비용(거리·시간·요금 등) 값이 매겨진 그래프 | 통행료가 다른 도로망 지도 |
| 완화(Relaxation) | `Dist[V] > Dist[U] + Weight(U,V)`이면 `Dist[V]`를 갱신하는 연산, 세 알고리즘 공통의 핵심 동작 | "이 우회로가 더 싸네, 갱신!" |
| 다익스트라(Dijkstra) | 단일 출발점, 음수 가중치 불가, 가장 가까운 정점부터 확정하는 그리디 알고리즘 | 가장 짧은 밧줄부터 하나씩 확정 |
| 벨만-포드(Bellman-Ford) | 단일 출발점, 음수 가중치·음수 사이클 탐지 가능, 모든 간선을 반복 완화 | 모든 도로 비용을 며칠에 걸쳐 재확인 |
| 플로이드-워셜(Floyd-Warshall) | 모든 정점 쌍(N:N) 최단 거리, 동적 계획법(013) 기반 3중 루프 | 전 역 간 모든 티켓 가격표 완성 |
| 우선순위 큐(Min-Heap) | 다익스트라에서 "지금까지 가장 가까운 미확정 정점"을 O(log V)에 꺼내는 자료구조 | 대기표 중 최우선 순번을 즉시 뽑는 기계 |
| 음수 가중치 | 간선 비용이 음수인 경우(예: 차익거래에서 환전 시 이익 발생) | 지나가면 오히려 돈이 생기는 길 |
| 음수 사이클 | 사이클을 돌 때마다 총 비용이 계속 줄어드는(무한히 작아지는) 사이클 | 돌수록 이득이 커지는 무한 루프 |

## 깊이 이해

### 완화(Relaxation) — 세 알고리즘의 공통 심장
세 알고리즘 모두 겉모습은 다르지만 내부에서 반복하는 연산은 동일하다: 정점 U를 거쳐 V로 가는 비용(`Dist[U] + Weight(U,V)`)이 지금까지 알고 있던 V까지의 최단 거리(`Dist[V]`)보다 작다면 `Dist[V]`를 갱신한다. 예를 들어 현재 `Dist[V] = 10`인데 U를 거쳐 가면 `Dist[U](=3) + Weight(U,V)(=4) = 7`이 나온다면, 7 < 10이므로 `Dist[V]`를 7로 갱신한다. 세 알고리즘의 차이는 "이 완화를 어떤 순서로, 몇 번 반복하는가"에 있을 뿐이다.

### 다익스트라 — 그리디가 성립하는 이유와 무너지는 이유
다익스트라는 "지금까지 확정된 것 중 가장 가까운 정점은, 이후 어떤 경로를 거쳐도 더 짧아질 수 없다"는 전제로 정점을 하나씩 확정해 나간다. 이 전제가 성립하려면 간선 가중치가 모두 0 이상이어야 한다 — 음수 간선이 있으면 나중에 "더 먼 것처럼 보였던" 경로가 음수 간선을 거쳐 갑자기 더 짧아질 수 있어, 이미 확정한 정점의 거리가 틀렸는데도 다시 고치지 않는다. 예를 들어 A→B(가중치 5)로 B를 5로 확정했는데, 나중에 A→C(가중치 2)→B(가중치 -10)라는 경로가 발견되면 실제 최단 거리는 -8이지만, 다익스트라는 B를 이미 확정해 다시 보지 않으므로 이 경로를 놓친다. 정상 동작 시 시간복잡도는 우선순위 큐를 쓰면 O(E log V)로, 정점 수 V=10,000, 간선 수 E=50,000인 그래프에서도 수십만 번의 연산으로 끝난다.

### 벨만-포드 — 느리지만 음수를 견디는 이유
벨만-포드는 "가장 가까운 것부터 확정"하는 전제 자체를 버리고, 모든 간선에 대해 완화를 정확히 V-1번(V는 정점 수) 반복한다. 왜 V-1번인가 하면, 최단 경로는 사이클이 없는 한 최대 V-1개의 간선으로 구성되므로, V-1번 반복하면 아무리 먼 경로라도 완화가 전파될 시간이 충분하기 때문이다. 정점이 5개인 그래프라면 4번만 반복해도 모든 최단 경로가 확정된다. V번째 반복에서도 여전히 갱신이 일어난다면, 그것은 최단 경로가 아니라 음수 사이클이 존재한다는 증거다 — 이 특성으로 벨만-포드는 음수 사이클 탐지에도 쓰인다. 시간복잡도는 O(V×E)로, 같은 V=10,000·E=50,000 그래프라면 5억 번 연산이 필요해 다익스트라보다 훨씬 느리다.

### 플로이드-워셜 — 모든 쌍을 한 번에, 그러나 비용은 세제곱
플로이드-워셜은 "정점 K를 경유했을 때 i→j가 더 짧아지는가"를 모든 K, i, j 조합에 대해 확인하는 동적 계획법(013)이다. `Dist[i][j] = min(Dist[i][j], Dist[i][k] + Dist[k][j])`라는 점화식을 K=1부터 V까지 순서대로 모든 i, j에 적용한다. 이렇게 하면 3중 루프이므로 O(V³)이다. 정점이 100개면 100만 번이라 순식간이지만, 정점이 1,000개면 10억 번 연산이 되어 대규모 그래프에서는 감당하기 어렵다. 대신 구현이 3중 for문뿐이라 간단하고, 모든 정점 쌍의 최단 거리를 한 번에 얻는다는 것이 장점이다.

### 판별 기준 — 언제 무엇을 쓰는가
출발점이 하나이고 음수 간선이 없다면 다익스트라(가장 빠름), 출발점이 하나이고 음수 간선이 있을 수 있다면 벨만-포드, 모든 정점 쌍의 거리가 전부 필요하고 정점 수가 크지 않다면(수백 개 수준) 플로이드-워셜을 쓴다. 실무 대규모 라우팅 네트워크는 정점(라우터) 수가 많아 플로이드-워셜을 감당할 수 없으므로 다익스트라 계열(OSPF)이 표준이다.

### 비유
다익스트라는 눈을 감고 여러 개의 밧줄을 쥔 채 가장 팽팽한(짧은) 것부터 하나씩 당겨 확정하는 것과 같다. 벨만-포드는 모든 톨게이트 비용표를 정해진 날 수만큼 반복해서 다시 확인하는 것과 같다. 플로이드-워셜은 전국 모든 역 사이의 티켓 가격표를 펼쳐놓고 "이 역을 거쳐 가면 더 싼가?"를 모든 역에 대해 전수 계산하는 것과 같다.

## 연결 개념
- 010 그래프 탐색 — BFS를 가중치 환경으로 확장한 것이 다익스트라
- 013 동적 프로그래밍 — 플로이드-워셜이 기반으로 삼는 패러다임

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 가중치 그래프 모델에서 두 노드 간의 비용 합을 최소화하기 위해, 그리디 또는 동적 계획법 기반으로 엣지 릴렉세이션(Edge Relaxation)을 수행하는 알고리즘이다.
> 2. **가치**: L3 라우터 패킷 포워딩 경로 산출 및 모빌리티 배차 등 물류/통신 네트워크의 트래픽 병목과 지연 시간을 통제한다.
> 3. **판단 포인트**: 타겟이 1:N인지 N:N인지, 그리고 네트워크 내 음수 사이클이 존재하는지에 따라 다익스트라, 벨만-포드, 플로이드-워셜을 스위칭해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3종의 구조적 한계와 차이 구분 | 음수 가중치 대응력, 단일 출발(1:N) vs 모든 쌍(N:N) | 다익스트라만 쓰고 벨만-포드와 플로이드의 차이를 누락 |
| 엣지 릴렉세이션 메커니즘 이해 | `D[V] > D[U] + Weight(U,V)` 갱신 수식 | 알고리즘 이름만 나열하고 공통된 동작 수식을 미기재 |

> 요약: 세 알고리즘은 모두 "기존 최단거리보다 경유하는 거리가 더 짧으면 갱신한다"는 동일한 완화(Relaxation) 원리를 각자의 제어 흐름으로 풀어낸 것이다.

## Ⅰ. 개요 및 필요성

- 정의: 가중치 그래프에서 시작 정점부터 도착 정점까지의 간선 가중치 합이 최소가 되는 경로를 산출하는 탐색 기법
- 배경: 단순 너비 우선 탐색(BFS)은 간선 통과 횟수만 최소화하므로, 통신망의 대역폭/지연율 등 비대칭적 가중치를 반영 불가
- 필요성: OSPF 같은 라우팅 프로토콜에서 혼잡도(Cost)를 반영하여 밀리초 단위로 패킷 경로를 재계산(Convergence)하기 위해 필수

---

## Ⅱ. 3대 최단 경로 구조 및 메커니즘

```text
[요청] -> 타겟 범위(1:N / N:N) 확인 -> [음수 간선 존재 검증] -> 알고리즘 선택 -> 릴렉세이션 반복 -> 거리 배열 완성
```

| 알고리즘 | 탐색 범위 | 시간복잡도 | 메커니즘 특이사항 |
|:---|:---|:---|:---|
| 다익스트라 (Dijkstra) | 단일 출발점 | O(E log V) | 힙 기반 그리디 탐색, **음수 간선 처리 불가** |
| 벨만-포드 (Bellman-Ford) | 단일 출발점 | O(V * E) | 모든 간선을 V-1번 반복 갱신, **음수 사이클 탐지 가능** |
| 플로이드-워셜 | 모든 정점 쌍 | $O(V^3)$ | DP 기반 인접 행렬 3중 루프 갱신 (거쳐가는 정점 기준) |

> 요약: 다익스트라는 압도적으로 빠르지만 음수 제약이 있고, 플로이드는 구현이 단순하지만 노드가 많아지면 $O(V^3)$으로 시스템이 마비된다.

---

## Ⅲ. 동작원리 및 다익스트라 탐색 흐름도

```text
거리 배열 무한대 초기화 -> 시작점 Min-Heap 삽입 -> Pop(가장 싼 노드 U 추출) 
                         -> U 인접 간선 스캔 -> [ D[V] > D[U] + W(U,V) ] 조건 만족 시 갱신 후 큐에 삽입
```

| 단계 | 처리 내용 | 검증 기준 (수식) |
|:---:|:---|:---|
| 1 | 자료구조 초기화 | 최단거리 테이블 `Dist[] = Infinity`, `Dist[Start] = 0` |
| 2 | 최소 비용 노드 추출 | 우선순위 큐를 통해 미방문 노드 중 최소값 노드 U 선택 |
| 3 | 릴렉세이션 (완화) | 인접 노드 V에 대해 `Dist[V] > Dist[U] + Cost(U,V)` 검사 |
| 4 | 테이블 갱신 및 삽입 | 조건 충족 시 `Dist[V]` 값을 갱신하고 우선순위 큐에 `(비용, V)` 삽입 |

> 요약: 다익스트라는 "현재 가장 가까운 노드는 이후 어떤 우회로를 거쳐도 더 짧아질 수 없다"는 그리디 명제에 기반해 확정해 나간다.

## Ⅳ. 특징

| 구분 | 배열 기반 구현 | 힙(우선순위 큐) 기반 구현 | 판단 포인트 |
|:---|:---|:---|:---|
| 최소 비용 노드 탐색 | 미방문 노드 전체를 선형 스캔 O(V) | 우선순위 큐에서 추출 O(log V) | 그래프 밀집도 |
| 총 시간복잡도 | $O(V^2)$ | O((V+E) log V) | 밀집 그래프($V^2$ 유리) vs 희소 그래프(E log V 유리) |
| 구현 복잡도 | 배열과 반복문만으로 구현 단순 | 힙 자료구조와 감소 키(decrease-key) 처리 필요 | 개발 난이도 vs 대규모 성능 요구 |
| 적용 사례 | 노드 수가 적은 밀집 그래프(소규모 지도) | 대규모 희소 그래프(라우터 토폴로지, 대형 도로망) | 노드 대비 간선 비율 |

> 요약: 밀집 그래프는 배열 기반이, 희소 그래프는 힙 기반이 유리하며 실무 대형 네트워크는 대부분 희소하므로 힙 기반 구현이 표준이다.

|:---|:---|:---|:---|:---|
| 최적 적용망 | 전국 도로망 내비게이션 | 차익 거래(Arbitrage) 금융망 | 소규모 인트라넷 라우팅 | 노드 수(V) 크기 제약 |
| 음수 가중치 | 탐색 결과 붕괴 | 지원 (음수 사이클 마킹) | 지원 (자기자신 거리 음수 시 루프) | 역방향 비용 존재 유무 |
| 자료 구조 | 인접 리스트 + Heap Array | 인접 리스트 (Edges) | V x V 2차원 인접 행렬 | 희소 그래프 vs 밀집 그래프 |
| 상태 갱신 방식 | 정점 중심 (인접 간선) | 간선 중심 (모든 간선 강제) | 경유지 중심 (모든 K 조합) | 분산 처리 적합성 |

> 요약: 10만 개 이상의 대형 노드 네트워크에서는 다익스트라만이 유일한 현실적 대안이며, A* 알고리즘 등 휴리스틱 기법을 더해 탐색 공간을 더 좁힌다.

| 리스크 | 발생 원인 | 대응 기법 | 확인 지표 |
|:---|:---|:---|:---|
| 라우팅 블랙홀 | 벨만-포드 기반 프로토콜(RIP)에서 단절 시 무한 루프 발생 | Split Horizon 규칙 선제 적용 | 라우팅 홉 수(Hop Count) 도달률 |
| 다익스트라 지연 | 업데이트 빈발 시 Heap 트리 Re-build 지연 | 피보나치 힙 적용으로 연산 O(1) 달성 | 경로 재계산 Convergence Time |

> 요약: 토폴로지 변경 시 기존 최단 경로가 무효화되므로, 재계산 타임아웃을 방어하는 자료구조 튜닝이 필수적이다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. L3 라우터 최단 경로 선출 (OSPF): 링크 상태 라우팅 프로토콜에서 각 라우터가 토폴로지 맵을 기반으로 다익스트라를 돌려 최적 넥스트 홉 포워딩 테이블 구축
2. 금융 차익 거래 탐지 로직: 외환 환율을 가중치로 둔 그래프에 로그 변환 후 벨만-포드를 적용, 환전할수록 이득인 "음수 사이클"을 색출
3. 내비게이션 A* 길찾기: 다익스트라 기반 위에 목적지까지의 직선거리 예상치(휴리스틱)를 덧붙여 엉뚱한 방향 탐색을 차단하고 런타임 최적화

**결론 (2줄):**
- 기술사 판단: 최단 경로는 인프라 규모(V, E)와 가중치 물리적 성질(음수 허용 여부)에 따라 3대 알고리즘과 휴리스틱 튜닝을 스위칭하는 결단이다.
- 향후 방향: 실시간 클라우드 트래픽 제어에서는 단일 최단 경로뿐만 아니라 트래픽을 다중 경로로 분산시키는 ECMP(Equal-Cost Multi-Path) 최적화로 확장 중이다.
