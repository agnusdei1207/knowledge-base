## Ⅰ. 개요
- **정의**: 전송·저장 중 발생한 비트 오류를 검출하거나 원래 값으로 복원하는 기법
- **배경/필요성**: 채널 잡음으로 비트 반전이 불가피하므로, 수신 측이 오류 유무를 판단하고 재전송 없이 복원할 수단이 필요함
- **비유**: 편지에 체크리스트를 동봉해 받는 사람이 누락·변조 여부를 스스로 확인하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 검출과 정정의 차이를 구분하는지 확인 | 해밍 거리와 정정 능력의 관계 | 패리티는 1비트 검출만 가능, CRC는 검출 전용임을 혼동하지 말 것 |

> 요약: 비트 오류를 잉여 비트로 검출·정정하여 신뢰성을 확보하는 부호화 기법임

## Ⅱ. 구성요소
```text
  송신 데이터
       |
       v
  +----------+     +----------+     +----------+
  | 부호화기  |---->| 채널     |---->| 복호화기  |
  | (잉여비트 |     | (잡음)   |     | (검출/   |
  |  부가)    |     |          |     |  정정)    |
  +----------+     +----------+     +----------+
       |                                  |
   코드워드 생성                     오류 판정/복원
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 패리티 비트 | 1비트를 추가하여 1의 개수를 짝수/홀수로 맞춤, 1비트 오류 검출 가능 | 짐 개수를 세어 빠진 것이 있는지 확인하는 체크 |
| CRC | 생성 다항식으로 나눗셈 후 나머지를 부가하여 버스트 오류를 검출함 | 계좌 이체 시 검증 번호로 금액 변조를 탐지하는 원리 |
| 해밍 코드 | 여러 패리티 비트를 데이터 사이에 배치하여 1비트 오류 위치를 특정·정정함 | 좌석 번호별 출석 체크로 결석자를 정확히 찾는 방식 |
| 신드롬 | 수신 코드워드를 검사 행렬과 곱해 오류 위치를 가리키는 벡터 | 진찰 결과로 아픈 부위를 특정하는 진단서 |

> 요약: 패리티·CRC·해밍 코드가 잉여 비트를 통해 오류를 검출하거나 정정함

## Ⅲ. 절차
```text
  1.인코딩       2.전송          3.신드롬계산     4.정정/재전송
  (잉여비트부가)  (채널통과)      (오류위치판별)   (비트반전복원)
   |              |               |               |
   +---코드워드--->+---수신워드---->+---신드롬------>+
  데이터+패리티   잡음혼입        검사행렬적용     오류비트플립
```
- 1단계: 송신 측이 데이터에 패리티·CRC·해밍 잉여 비트를 부가하여 코드워드를 생성함
- 2단계: 코드워드가 채널을 통과하며 잡음에 의해 비트 반전이 발생할 수 있음
- 3단계: 수신 측이 검사 행렬 또는 다항식 나눗셈으로 신드롬을 계산하여 오류 유무와 위치를 판별함
- 4단계: 신드롬이 0이 아니면 해당 비트를 반전(정정)하거나 재전송을 요청(ARQ)함

> 요약: 인코딩 → 전송 → 신드롬 계산 → 정정/재전송의 4단계로 오류를 처리함

## Ⅳ. 문제점
- 잉여 비트 오버헤드: 정정 능력을 높일수록 잉여 비트가 증가하여 유효 전송률이 저하됨
- 다중 비트 오류 한계: 단순 해밍 코드는 2비트 이상 동시 오류 시 오검출 위험이 존재함
- 버스트 오류 취약성: 패리티 기반 기법은 연속 비트 반전(버스트 오류)에 대한 검출 능력이 제한적임

> 요약: 오버헤드 증가·다중 비트 한계·버스트 오류 취약성이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 인터리빙을 적용하여 버스트 오류를 분산시킨 뒤 단일 비트 정정 코드로 처리함
2. 중기: SEC-DED(단일 정정·이중 검출) 확장 해밍 코드로 2비트 오류까지 검출함
3. 장기: LDPC·터보 코드 등 반복 복호 기법을 도입하여 채널 용량에 근접한 정정 성능을 확보함

> 요약: 인터리빙 → SEC-DED 확장 → LDPC/터보 코드 순으로 정정 능력을 강화함

## Ⅵ. 전망
- 발전 방향: 5G·위성 통신에서 Polar 코드 등 채널 용량 달성 부호가 표준으로 채택되는 추세임
- 기술사적 판단: ECC 메모리·저장장치에서 오류 정정은 시스템 신뢰성의 기본 요건으로 지속 확대됨
- 기술사 제언: 응용별 오류 특성(랜덤/버스트)을 분석하여 적정 부호율과 정정 기법을 선택해야 함
