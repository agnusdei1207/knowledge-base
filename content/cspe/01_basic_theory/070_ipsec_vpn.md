## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 애플리케이션(웹, 메일) 단에서 암호화를 챙기는 TLS와 달리, 아예 네트워크 3계층(Network Layer)의 바닥으로 내려가 IP 패킷 자체를 통째로 암호화하고 가상의 터널을 뚫어버리는 하부 인프라 보안 프로토콜이다.
> 2. **가치**: 회사의 전용선(Leased Line)을 깔려면 수억 원이 들지만, 누구나 보는 뻥 뚫린 인터넷망 위에 암호화된 가상의 전용선(Virtual Private Network, VPN)을 공짜로 깔아 본사-지사 간의 완벽한 폐쇄망을 구축하게 해준다.
> 3. **판단 포인트**: 데이터 내용물만 암호화하는 전송 모드(Transport)와 원래의 IP 헤더까지 몽땅 감싸서 출발지/도착지 추적조차 불가능하게 만드는 터널 모드(Tunnel Mode)의 아키텍처 차이를 명확히 구분해야 한다.

## 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| IPsec | IP 네트워크 계층(L3)에서 패킷의 인증·암호화·무결성을 제공하는 프로토콜 스위트 | IP 패킷 자체를 강철 금고에 넣어 보내는 네트워크 계층 보안 |
| VPN (가상 사설망) | 공용 인터넷 위에 암호화 터널을 뚫어 마치 전용선처럼 사용하는 가상 네트워크 | 고속도로(인터넷) 밑에 몰래 뚫은 비밀 지하 터널 |
| 전송 모드 (Transport Mode) | IP 헤더는 유지하고 페이로드(데이터)만 암호화하는 IPsec 모드 | 편지 내용만 잠그고 봉투 겉면(주소)은 보이게 두는 방식 |
| 터널 모드 (Tunnel Mode) | 원래 IP 헤더까지 통째로 암호화하고 새 IP 헤더를 덧씌우는 IPsec 모드 | 편지를 금고에 넣고 금고에 새 주소표를 붙여 보내는 완전 은닉 |
| ESP (Encapsulating Security Payload) | 데이터 암호화(기밀성)와 인증을 동시에 수행하는 IPsec의 핵심 프로토콜 | 내용물을 숨기면서 동시에 봉인 스티커까지 붙이는 이중 포장 |
| NAT-Traversal (NAT-T) | NAT 환경에서 IPsec 패킷이 차단되지 않도록 UDP로 한 번 더 감싸는 우회 기법 | 검문소를 무사히 통과하기 위해 군복 위에 민간인 옷을 걸치는 위장술 |

## Ⅰ. 개요 및 필요성
- **개요**: IPsec은 IP 프로토콜 수준에서 데이터 무결성, 송신자 인증, 기밀성(암호화)을 제공하기 위해 IETF에서 고안한 프로토콜 스위트(AH, ESP, IKE의 묶음)이며, 기업용 VPN(가상 사설망)을 구성하는 핵심 코어 기술이다.
- **배경**: 초창기 IP(IPv4)는 보안이란 개념 자체가 없는 순진한 통신 규약이었다. 누가 데이터를 가로채든, IP 주소를 위조(Spoofing)하든 막을 방법이 없어 해커들의 놀이터였다.
- **필요성**: 서울 본사와 부산 지사가 통신할 때마다 모든 프로그램 개발자가 일일이 암호화 코드를 짜는 건 불가능했다. 아예 운영체제와 라우터의 '네트워크 통신 밑단'에서 모든 트래픽을 일괄적으로 묻지도 따지지도 않고 암호화해 줄 강력한 터널 굴착기가 필요했다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
       [전송 모드 (Transport Mode)]               [터널 모드 (Tunnel Mode) - VPN의 핵심!]
  (보통 내부 네트워크망 안에서 단말기끼리 씀)       (인터넷이라는 지옥을 건널 때 라우터끼리 씀)

  ┌─────┬──────────┬────────┐                 ┌─────┬──────┬──────────┬────────┐
  │ 원본 │ IPsec 헤더 │ 원본 데이터 │                 │ NEW │ IPsec │  원본 IP │ 원본 데이터 │
  │ IP  │ (AH/ESP) │  (암호화)  │                 │ IP  │ 헤더  │ (암호화) │  (암호화)  │
  └─────┴──────────┴────────┘                 └─────┴──────┴──────────┴────────┘
  ▶ 원래 길 안내(IP) 정보는 노출됨!                 ▶ 기존 IP마저 암호화해버리고 새로운 포장지로 덮음!
                                                누가 진짜 데이터를 보냈는지 해커가 절대 추적 불가!
```

- **1단계 [IKE (키 교환 및 협상)]**: 터널을 뚫기 전에 양쪽 라우터(또는 게이트웨이)가 "우리 무슨 암호 쓸래? 128비트? 256비트?"라고 서로 합의(SA, Security Association)하고, 안전하게 대칭키를 나눠 가지는 전초전(IKE 프로토콜)을 치른다.
- **2단계 [AH (인증 헤더) 작동]**: 데이터가 조작되지 않았는지(무결성) 검사하고, "이 패킷은 우리 본사에서 온 게 맞다"라고 인증해 주는 도장을 패킷에 쾅 찍는다. (단, 암호화는 안 해줘서 데이터 내용물은 다 보임).
- **3단계 [ESP (암호화 페이로드) 작동]**: 내용물이 안 보이게 AES 같은 알고리즘으로 데이터를 꽁꽁 암호화(기밀성 제공)하는 실질적인 보호막 역할을 한다. (현실에서는 귀찮아서 AH는 잘 안 쓰고 ESP 하나로 인증과 암호화를 다 해버린다).
- **4단계 [터널링 전송 (Tunneling)]**: 터널 모드 적용 시, 서울 본사 직원의 IP(192.168.0.1)가 적힌 원본 패킷 전체를 ESP가 암호화해 버린 뒤, 겉면에 '서울 라우터 $\to$ 부산 라우터'라는 가짜 껍데기 IP를 덧붙여(캡슐화) 인터넷 바다로 쏘아 보낸다.

## Ⅲ. 비교 및 연결

| 비교 축 | TLS/SSL VPN (일반인용) | IPsec VPN (기업 인프라용) |
|:---|:---|:---|
| **작동 계층** | L4/L7 (전송/응용 계층) | **L3 (네트워크 계층)** |
| **적용 범위** | 웹 브라우저(특정 앱) 통신만 암호화 | PC에서 나가는 **모든 트래픽 100% 암호화** |
| **설치 편의성**| 클라이언트(브라우저)만 있으면 접속 끝 | 운영체제에 전용 클라이언트(소프트웨어) 설치 필수 |
| **주사용처** | 재택근무자의 사내 인트라넷 가벼운 웹 접속 | **본사와 지사 간의 네트워크 통째 연결 (Site-to-Site)** |
| **방화벽 통과**| 포트 443(HTTPS)을 쓰므로 프리패스 무사통과 | 전용 프로토콜 번호라 방화벽/NAT에서 툭하면 막힘 |

> ※ **연결 포인트**: IPsec은 OS 커널 단에서 도는 무거운 인프라라서, 외부 카페에서 노트북을 켜는 재택근무자에게 세팅을 시키면 툭하면 연결이 끊기고 방화벽에 막혀 IT팀의 전화기에 불이 난다. 그래서 개별 사용자의 원격 접속(Client-to-Site)용으로는 세팅이 필요 없는 'TLS/SSL VPN'이 대세를 먹었고, 'IPsec'은 라우터 기계끼리 한 번 세팅해 두면 영구적으로 뚫려있는 본사-지사 간 지점 연결(Site-to-Site)의 제왕으로 양분되었다.

## Ⅳ. 실무 적용 및 기술사 판단

- **적용 사례 1 (글로벌 Site-to-Site VPN 구축)**: 서울 본사와 뉴욕 지사 간에 매월 1천만 원짜리 물리적 해저 케이블 전용선을 깔 수 없다. 대신 양쪽 인터넷 공유기(VPN 라우터)에 IPsec 터널 모드를 세팅한다. 서울 직원이 10.0.0.5(뉴욕망 IP)로 핑을 때리면, 라우터가 알아서 IPsec으로 캡슐화해 공망을 건너 뉴욕 라우터에 도착하고, 껍데기를 벗고 뉴욕 사내망으로 침투하는 완벽한 가상 사설망이 완성된다.
- **적용 사례 2 (IPv6의 기본 보안 규격)**: 과거 IPv4 시대에는 IPsec이 "옵션"이라서 별도 프로그램을 깔아야 했지만, 차세대 인터넷 주소 체계인 IPv6에서는 아예 프로토콜 스펙 자체에 IPsec을 의무(Mandatory)로 박아 넣어서 설계했다. (현재는 강제 조항에서 다시 옵션으로 풀리긴 했음).
- **기술사 판단**: IPsec 터널 모드의 최대 적폐는 **NAT(네트워크 주소 변환)와의 충돌**이다. IPsec(AH)은 IP 헤더가 단 1비트라도 조작되면 위조 패킷으로 간주해 버리는데, 가정용 공유기(NAT)는 인터넷으로 나갈 때 내부 IP를 사설 IP로 변환(조작)하므로 IPsec이 "위조당했다!"라며 패킷을 다 버려버린다. 따라서 아키텍트는 반드시 NAT-Traversal(NAT-T) 기능을 활성화하여 IPsec 패킷을 UDP(포트 4500) 껍데기로 한 번 더 싸서 NAT의 감시를 무사히 우회하도록 설계해야 한다.

## Ⅴ. 기대효과 및 결론

- **기대효과**: 수백만 원짜리 하드웨어 전용선(Leased Line) 시장을 붕괴시키고, 인터넷이라는 값싼 공용 망을 세상에서 가장 안전하고 사적인 기업 전용 고속도로로 탈바꿈시킨 네트워크 가상화의 승리다.
- **향후 발전 방향**: IPsec의 극악무도한 설정 복잡도(IKE 세팅, 인증서, 파라미터 수천 줄)와 코드의 비대함을 혁파하기 위해, 코드 단 4,000줄로 구성되어 엄청나게 가볍고 암호화 속도가 압도적으로 빠른 최신 L3 VPN 프로토콜인 **WireGuard(와이어가드)**가 등장하여 리눅스 커널에 편입되며 IPsec의 자리를 맹렬히 위협하고 있다.

### 📌 관련 개념 맵
- **ESP (Encapsulating Security Payload)**: IPsec 삼총사 중 실질적인 전투원. 암호화와 인증을 동시에 다 해주며, 실제 패킷 내용물을 남들이 절대 못 보게 꽁꽁 싸매버리는 포장지 역할.
- **VPN (Virtual Private Network)**: 내 PC와 회사 사이에 실제로 물리적인 구리선이 깔린 건 아니지만, 암호화 기술(IPsec 등)을 통해 마치 나 혼자만 쓰는 지하 비밀 터널(가상 전용선)이 뚫린 것과 완벽히 같은 효과를 내는 기술.

### 📈 관련 키워드 및 발전 흐름도
`IPv4 (보안 개념 부재)` $\to$ `IPsec (네트워크 계층 암호화 발명)` $\to$ `터널 모드 기반 VPN 상용화` $\to$ `NAT-T (공유기 충돌 문제 극복)` $\to$ `WireGuard (초경량 차세대 VPN)`

### 👶 어린이를 위한 3줄 비유 설명
1. 중요한 편지를 그냥 우체국에 맡기면(일반 인터넷) 배달부 아저씨나 도둑이 편지 내용을 몰래 뜯어볼 수 있어요.
2. IPsec 터널 모드는 편지를 '절대 깨지지 않는 강철 금고'에 넣고, 겉면에는 발송자 이름을 안 적은 채 "비밀 우체국장 앞"이라고 가짜 주소(캡슐화)를 적어서 보내는 거예요.
3. 무사히 도착하면 비밀 우체국장이 강철 금고를 열어 원래 편지를 꺼낸 뒤, 진짜 목적지로 조용히 배달해 주는 완벽한 비밀 수송 작전이랍니다!
