## Ⅰ. 개요
- **정의**: 삽입·삭제 위치를 제한하여 특정 접근 순서를 보장하는 선형 자료구조 집합
- **배경/필요성**: 범용 리스트는 임의 위치 접근을 허용하므로 순서 제약이 필요한 문제(함수 호출 복귀, 작업 스케줄링 등)에 구조적 보장이 부족함
- **비유**: 스택은 접시 쌓기(위에서만 꺼냄), 큐는 매표소 줄(먼저 온 사람이 먼저 나감), 덱은 양쪽 문이 있는 터널

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LIFO·FIFO·양방향 접근 원리 구분 | 각 구조의 연산 제약과 대표 응용 | 덱을 스택+큐 상위 개념으로 설명할 것 |

> 요약: 접근 위치 제한으로 LIFO·FIFO·양방향 순서를 구조적으로 보장하는 자료구조임

## Ⅱ. 구성요소
```text
  Stack (LIFO)          Queue (FIFO)          Deque (양방향)
  +--------+            +--------+            +--------+
  | top -> |  push/pop  |front   |  enq/deq   |front   | push/pop
  |  data  |            |  data  |            |  data  |  양쪽 가능
  |  data  |            |  data  |            |  data  |
  |  data  |            |   rear |            |   rear |
  +--------+            +--------+            +--------+
   한쪽 끝만             앞: 삭제              앞/뒤 모두
                         뒤: 삽입              삽입·삭제
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Stack | `top`에서만 삽입(`push`)·삭제(`pop`)하는 LIFO 구조 | 접시 더미 — 맨 위만 조작 가능 |
| Queue | `rear`에서 삽입(`enqueue`), `front`에서 삭제(`dequeue`)하는 FIFO 구조 | 매표소 줄 — 먼저 선 사람이 먼저 처리됨 |
| Deque | 양쪽 끝에서 삽입·삭제가 모두 가능한 이중 종단 구조 | 양쪽 문 터널 — 어느 쪽으로든 출입 가능 |
| `top`/`front`/`rear` | 각 구조에서 연산이 발생하는 경계 포인터 | 줄의 맨 앞·맨 뒤 표시판 |
| Circular Buffer | 큐를 배열로 구현 시 `front`·`rear`를 순환시켜 공간을 재활용하는 기법 | 회전초밥 벨트 — 끝에 도달하면 처음으로 돌아감 |

> 요약: Stack(LIFO)·Queue(FIFO)·Deque(양방향)는 경계 포인터로 접근 위치를 제한함

## Ⅲ. 절차
```text
  연산 요청          경계 포인터 확인     데이터 삽입/삭제     포인터 갱신
  (push/enq/등)     (overflow/underflow) (top/front/rear)    (경계 이동)
       |                  |                   |                   |
       +---유효성 검사---->+---조건 충족------->+---반영------------>+
     연산 종류 판별     공간/데이터 존재    배열/노드에 반영    top/front/rear 조정
```
- 1단계: 요청된 연산 종류(push/pop/enqueue/dequeue 등)를 판별함
- 2단계: 경계 포인터를 확인하여 오버플로(공간 부족)·언더플로(데이터 없음) 여부를 검사함
- 3단계: 조건 충족 시 해당 위치에 데이터를 삽입하거나 삭제함
- 4단계: `top`/`front`/`rear` 포인터를 갱신하여 다음 연산 위치를 반영함

> 요약: 연산 판별 → 경계 검사 → 데이터 반영 → 포인터 갱신 순으로 O(1) 연산을 수행함

## Ⅳ. 문제점
- 오버플로/언더플로: 배열 기반 구현에서 고정 크기 초과 삽입 또는 빈 구조 삭제 시 오류 발생 — 런타임 예외로 이어짐
- 임의 접근 불가: 중간 요소에 접근하려면 전체 pop/dequeue 필요 — 탐색 용도에 부적합함
- 큐의 공간 낭비: 선형 배열 큐에서 `front` 이동 후 앞쪽 공간이 재사용 불가 — 유효 용량이 지속적으로 감소함

> 요약: 고정 크기 한계, 중간 접근 불가, 선형 큐 공간 낭비가 주요 제약임

## Ⅴ. 개선방안
1. 단기: 동적 배열 또는 연결 리스트(006 참조) 기반 구현으로 오버플로 방지
2. 중기: 인덱스 접근이 필요한 경우 보조 자료구조(해시맵 등)를 병행하여 탐색 지원
3. 장기: 원형 버퍼(Circular Buffer)를 적용하여 `front` 이동 후 공간을 순환 재활용

> 요약: 동적 크기 → 보조 구조 병행 → 원형 버퍼로 단계적 제약을 해소함

## Ⅵ. 전망
- 발전 방향: Lock-Free Stack/Queue 등 비차단 동시성 구조가 멀티스레드 환경에서 확산됨
- 기술사적 판단: 문제 특성에 맞는 접근 순서 제약(LIFO/FIFO/양방향)을 선택하는 설계 역량이 핵심임
- 기술사 제언: 실시간 시스템에서는 우선순위 큐(힙 기반)와의 결합을 고려하여 스케줄링 효율을 확보할 필요
