## 미리 알고가기

- 후입선출(LIFO, Last-In First-Out): 마지막에 삽입한 데이터가 먼저 제거되는 규칙임
- 선입선출(FIFO, First-In First-Out): 먼저 삽입한 데이터가 먼저 제거되는 규칙임
- 양방향 큐(Deque, Double-Ended Queue): 앞(Front)과 뒤(Rear)에서 삽입·삭제를 허용하는 구조임
- 슬라이딩 윈도우: 연속 구간을 이동하며 구간 내 최댓값 같은 집계값을 갱신하는 기법임
- 오버플로(Overflow): 고정 크기 저장공간이 가득 찬 상태에서 삽입을 요청한 경우임
- 언더플로(Underflow): 자료구조가 비어 있는 상태에서 삭제를 요청한 경우임
- 원형 큐: 배열의 끝과 시작을 연결해 빈 공간을 재사용하는 큐 구현임
- Push·Pop·Enqueue·Dequeue: 스택과 큐의 삽입·삭제 연산임
- Top·Front·Rear 포인터: 스택 상단과 큐·덱의 앞·뒤 위치를 나타냄

## 작성 근거(검토용)

- **방향성**: 스택·큐·덱은 접근 끝점을 제한해 처리 순서를 $O(1)$로 고정하므로, 후입·선입·양방향 중 업무가 요구하는 순서와 맞는 구조만 선택할 수 있고 고정 크기 구현이면 포화·공백 시 동작(오버플로 처리·역압)까지 함께 정해야 함
- **개요 구성**: 허용 끝점과 제거 순서를 함께 정의해 세 자료구조의 공통 판단축을 세움
- **Ⅱ. 특징 선정**: 끝점 제한에 따른 처리 순서 고정, 포인터 갱신 비용, 구현별 경계 관리는 선택과 검증의 핵심임
- **Ⅲ. 비교축 선정**: 처리 순서, 접근 위치, 대표 활용은 세 자료구조의 선택을 가름
- **Ⅳ. 구조 선정**: Top, Front, Rear 위치가 동작을 결정하므로 텍스트 모델로 배치함
- **Ⅴ. 절차 선정**: 연산 요청·상태 검사·데이터 처리·포인터 갱신 순서가 오버플로·언더플로가 발생하는 지점을 보여주므로 절차로 둠
- **Ⅵ. 실무 사례 선정**: 깊은 소프트웨어 의존성 그래프는 최대 탐색 깊이, 고정 크기 메시지 버퍼는 공백·포화 경계가 구현 검증의 핵심이라 남김
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 처리 순서·경계 조건 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 스택·큐·덱은 삽입·삭제가 허용되는 끝점과 제거 순서를 제한해 데이터 처리 순서를 통제하는 선형 자료구조임
- **배경/필요성**: 호출 이력·작업 대기열·버퍼링의 처리 순서를 통제하기 위해 입출력 규칙이 필요함

### 쉽게 이해하기 (학습용)
- 접시를 쌓아 위에서부터 꺼내거나, 줄을 서서 앞에서부터 나가거나, 양쪽 문으로 드나들 수 있는 통로처럼 어느 쪽으로 넣고 뺄 수 있는지를 미리 정해두는 것과 같음

## Ⅱ. 특징

- 접근 끝점을 제한해 탐색·스케줄링·버퍼링의 처리 순서를 고정함
- Top·Front·Rear 포인터만 갱신하므로 정상 조건의 삽입·삭제 비용은 $O(1)$임
- 고정 크기 배열 구현은 오버플로, 연결 리스트 구현은 포인터 정합성을 관리함

### 쉽게 이해하기 (학습용)
- 정해진 문으로만 드나들 수 있어 순서가 항상 같은 방식으로 정해짐
- 문 앞의 표지판(포인터)만 옮기면 되니 드나드는 데 오래 걸리지 않음
- 통로 크기가 정해져 있으면 꽉 찼을 때 못 들어가는 문제가, 줄줄이 이어 붙인 통로면 연결이 끊기지 않게 관리하는 문제가 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| **처리 순서** | 마지막에 넣은 원소부터 처리 | 먼저 넣은 원소부터 처리 | 앞과 뒤 중 선택한 끝의 원소부터 처리 |
| **접근 위치** | 한쪽 끝에서만 입출력 | 뒤에서 입력하고 앞에서 출력 | 양쪽 끝에서 입출력 |
| **대표 활용** | 재귀 호출 이력 | 작업 대기열 | 슬라이딩 윈도우 최댓값 |

> 요약: 역순 처리는 스택, 유입 순서 처리는 큐, 양방향 처리는 덱을 사용함.

### 쉽게 이해하기 (학습용)
- 나중에 쌓은 접시부터 꺼내는 방식(스택), 줄 선 순서대로 나가는 방식(큐), 양쪽 문으로 다 드나드는 방식(덱)은 어느 쪽 끝을 쓸 수 있느냐로 갈림

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 저장체 | 데이터를 보관하는 배열 또는 연결 리스트 |
| 제어 포인터 | 허용된 입출력 끝점의 위치 정보 |
| 상태 판정 | 원소 수와 포인터 위치로 공백·포화 여부를 구분하는 경계 조건 |
| 입출력 연산 | 허용된 끝점의 데이터 입력과 출력 |

```text
[ 선형 자료구조 입출력 모델 ]
Stack:        Top -> [D3] -> [D2] -> [D1]
Queue:  Front [D1] -> [D2] -> [D3] Rear
Deque:  Front <-> [D1] <-> [D2] <-> Rear
```

> 요약: 스택·큐·덱은 허용 끝점이 처리 순서와 경계 오류 지점을 결정함.

### 쉽게 이해하기 (학습용)
- 물건을 담아두는 통(저장체), 지금 어디까지 찼는지 가리키는 표지판(제어 포인터), 통이 비었는지 꽉 찼는지 확인하는 눈금(상태 판정)이 맞물려 드나듦을 관리함

## Ⅴ. 원리 및 절차 흐름도

```text
연산·끝점 확인 → 공백·포화 판정
                  ├─ 수행 불가 → 언더플로·오버플로 반환
                  └─ 수행 가능 → 데이터 삽입·삭제 → 포인터 갱신
```

1. **연산 요청**: 삽입(Push/Enqueue) 또는 삭제(Pop/Dequeue)를 받음
2. **상태 검사**: 삽입 전 Full, 삭제 전 Empty 여부를 확인함
3. **데이터 처리**: 허용된 끝점 위치에 데이터를 쓰거나 읽어 반환함
4. **포인터 갱신**: Top, Front, Rear를 이동하고 경계 규칙을 확인함

> 요약: 공백·포화 상태를 확인하고 허용된 끝점에서 처리한 뒤 포인터를 갱신함.

### 쉽게 이해하기 (학습용)
- 넣거나 뺄지 정하고, 통이 꽉 찼거나 비었는지 먼저 확인한 뒤, 정해진 문으로 물건을 처리하고, 표지판 위치를 옮기는 순서임

## Ⅵ. 실무 사례

1. 깊은 소프트웨어 의존성 그래프는 재귀 대신 명시적 스택으로 순회함
2. 고정 크기 메시지 버퍼는 원형 큐로 구현하고, 큐가 가득 차면 새 입력을 거부함

### 쉽게 이해하기 (학습용)
- 계단을 너무 깊이 내려가지 않도록 직접 표시하며 내려가거나, 원형 통로를 빙글빙글 돌며 자리를 재사용하는 대기줄과 같음

## Ⅶ. 결론

- 스택·큐·덱은 데이터가 들어오고 나가는 순서를 통제하며, 후입·선입·양방향 처리 목적에 맞게 선택해야 함
- 큐가 가득 차거나 비었을 때의 동작을 먼저 정하고, 처리 지연이 쌓이면 역압으로 입력을 제한해 메모리 고갈을 방지해야 함

### 쉽게 이해하기 (학습용)
- 통이 꽉 찼을 때 어떻게 할지 미리 정해두지 않으면 물건이 넘치므로, 밀려드는 속도가 빠르면 아예 입구에서 받는 속도를 늦춰야 함
