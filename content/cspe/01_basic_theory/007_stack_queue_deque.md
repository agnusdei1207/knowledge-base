## 핵심 답안

스택·큐·덱은 삽입과 삭제가 허용되는 위치를 기준으로 데이터 처리 순서를 통제하는 선형 추상 자료형(Abstract Data Type, ADT)이며, 내부 구현보다 **LIFO**, **FIFO**, **양단 접근**이라는 순서 규칙이 알고리즘 결과를 결정함.

```text
Stack: push/pop at top     Queue: enqueue rear, dequeue front     Deque: both ends
```

기술사 답안에서는 세 자료구조를 단순 용어로 나열하지 말고, 어떤 문제에서 처리 순서가 왜 중요한지와 구현 시 경계 조건을 함께 제시해야 함.

## 자료구조 비교

| 구분 | 스택(Stack) | 큐(Queue) | 덱(Deque) |
|:---|:---|:---|:---|
| 순서 규칙 | 후입선출(LIFO) | 선입선출(FIFO) | 양쪽 삽입·삭제 |
| 핵심 위치 | top | front, rear | front, rear |
| 주요 연산 | push, pop, peek | enqueue, dequeue | push/pop front, push/pop back |
| 대표 활용 | 함수 호출, 괄호 검사, DFS, undo | BFS, 작업 대기열, 메시지 버퍼 | 슬라이딩 윈도우, work stealing |
| 선택 기준 | 최근 상태를 먼저 처리 | 도착 순서와 공정성 보장 | 앞뒤 접근이 모두 필요 |

세 구조는 모두 연산 자체는 보통 `O(1)`로 설계하지만, 잘못된 순서 모델을 선택하면 알고리즘 의미가 달라짐.

## 구현 방식

| 구현 | 장점 | 주의점 |
|:---|:---|:---|
| 배열 | 연속 메모리, 캐시 효율, 단순 인덱스 | 고정 용량, overflow, 재할당 |
| 순환 배열 | 큐 공간 재사용, 메모리 효율 | front/rear 래핑, full/empty 구분 |
| 연결 리스트 | 크기 변화 유연, 양단 연결 쉬움 | 포인터 오버헤드, 동적 할당 비용 |
| lock-free 큐 | 동시성 성능 | ABA 문제, 메모리 가시성, 검증 난도 |

순환 큐에서는 "한 칸 비움" 정책 또는 `size` 카운터 정책을 명확히 해야 full과 empty를 구분할 수 있음.

## 알고리즘 적용 관점

| 문제 유형 | 선택 자료구조 | 이유 |
|:---|:---|:---|
| 괄호 검사, 호출 복귀 | 스택 | 최근 열린 항목부터 닫아야 함 |
| 깊이 우선 탐색(DFS) | 스택 또는 재귀 | 한 경로를 끝까지 따라감 |
| 너비 우선 탐색(BFS) | 큐 | 가까운 정점부터 레벨 순서로 처리 |
| 작업 스케줄링 | 큐 | 도착 순서와 공정성 유지 |
| 슬라이딩 윈도우 최대값 | 덱 | 오래된 값 제거와 양끝 후보 관리 |
| 병렬 work stealing | 덱 | 소유자는 한쪽, 다른 작업자는 반대쪽 접근 |

답안에서는 "스택은 DFS, 큐는 BFS"처럼 외우기보다, 방문 순서가 결과를 어떻게 바꾸는지 설명해야 함.

## 경계 조건과 운영 이슈

| 이슈 | 설명 | 대응 |
|:---|:---|:---|
| Underflow | 빈 구조에서 삭제 시도 | 예외, 실패 반환, 사전 empty 검사 |
| Overflow | 고정 배열 용량 초과 | 동적 확장, backpressure, 용량 산정 |
| 순환 인덱스 오류 | front/rear 갱신 실수 | 모듈러 연산과 테스트 케이스 표준화 |
| 동시 접근 경합 | 생산자·소비자 동시 접근 | 잠금, 조건 변수, lock-free 구조 |
| 순서 모델 오선택 | LIFO/FIFO 불일치 | 입출력 예제로 순서 검증 |

시스템 설계에서는 큐 길이, 대기 시간, 처리량, drop rate 같은 운영 지표가 자료구조 선택의 검증 기준이 됨.

## 오해와 감점 포인트

- **ADT와 구현 혼동**: 스택·큐는 규칙이고 배열·리스트는 구현 방법임
- **스택과 큐 순서 혼동**: LIFO와 FIFO를 바꾸면 DFS/BFS 결과가 달라짐
- **경계 조건 누락**: empty/full, overflow/underflow를 빼면 구현 답안이 약함
- **큐 공정성 과신**: 우선순위 큐, 지연 큐, 다중 큐는 단순 FIFO와 정책이 다름
- **동시성 누락**: 생산자·소비자 구조에서는 원자성, 메모리 가시성, blocking 정책이 필요함

## 답안 작성 포인트

1. 정의는 "삽입·삭제 위치로 처리 순서를 통제하는 선형 ADT"로 시작함
2. 스택, 큐, 덱을 LIFO/FIFO/양단 접근 기준으로 표 비교함
3. DFS, BFS, 작업 대기열, 슬라이딩 윈도우처럼 적용 사례를 순서 규칙과 연결함
4. 배열, 순환 배열, 연결 리스트 구현의 장단점을 언급함
5. 결론은 "자료구조 선택의 핵심은 Big-O보다 처리 순서와 경계 조건"으로 마무리함

> 기술사 관점에서 스택·큐·덱은 단순 자료구조가 아니라 탐색 순서, 스케줄링 공정성, 버퍼 안정성을 결정하는 순서 제어 도구임.
