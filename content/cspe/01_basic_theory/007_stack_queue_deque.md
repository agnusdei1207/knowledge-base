# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 스택·큐·덱은 데이터의 삽입·삭제가 일어나는 위치를 양 끝단으로 제한한 **선형 자료구조**이자, 구현 방식(배열이냐 연결 리스트냐)과 무관하게 "어떤 순서로 넣고 뺄 것인가"라는 정책만 정의하는 **추상 자료형(ADT, Abstract Data Type)**이다.
- **왜 필요한가**: 배열이나 연결 리스트를 아무 위치에서나 자유롭게 접근하도록 놔두면, 함수 호출 복귀 순서나 요청 처리 순서 같은 "순서 보장"이 코드마다 제각각으로 구현되어 버그가 생긴다. 입출구를 강제로 하나(또는 둘)로 좁혀 순서를 시스템적으로 보장하기 위해 만들어졌다.
- **핵심 직관**: 스택은 바닥이 막힌 프링글스 통(나중에 넣은 게 먼저 나옴), 큐는 한 줄 매표소(먼저 온 사람이 먼저 나감), 덱은 양쪽이 다 뚫린 파이프(양쪽에서 넣고 뺄 수 있음)다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 추상 자료형(ADT) | 내부 구현을 감추고 연산 규칙만 정의한 자료형 | 자판기 버튼 |
| 스택(Stack) | 후입선출(LIFO)만 허용 — Push/Pop 연산만 지원 | 프링글스 통 |
| 큐(Queue) | 선입선출(FIFO)만 허용 — Enqueue/Dequeue 연산만 지원 | 매표소 줄 |
| Front / Rear | 큐의 출구(맨 앞) / 입구(맨 뒤) | 줄의 맨 앞 / 맨 뒤 |
| 덱(Deque) | 양쪽 끝 모두에서 삽입·삭제 가능한 구조 | 양쪽이 뚫린 파이프 |
| 환형 큐(Circular) | 배열의 끝과 시작을 나머지 연산(%)으로 연결한 큐 | 원형 트랙을 도는 계주 |

## 깊이 이해
- **배경·문제의식**: 제약 없는 임의 접근(Random Access)은 서브루틴 복귀나 순차적 작업 처리 시 데이터 무결성을 훼손한다.
- **배열로 큐를 만들 때 생기는 함정**: 배열 기반 선형 큐에서 앞쪽 원소를 삭제하고 빈 공간을 두면, Rear 포인터가 배열 끝에 도달했을 때 실제로는 공간이 비어 있음에도 꽉 찼다고 오판하는 '가짜 오버플로우'가 발생한다. 이를 환형 큐로 해결한다.
- **배열 기반 vs 연결 리스트 기반**: 배열 기반은 캐시 지역성이 좋아 빠르지만 크기 확장이 어렵다. 연결 리스트 기반은 무한 확장이 가능하지만 포인터 오버헤드와 캐시 미스 비용을 지불해야 한다.
- **파생 구조**: 우선순위 큐는 FIFO 원칙을 깨고 우선순위가 높은 것을 먼저 처리하며, 락 프리 큐는 멀티 스레드 환경에서 동시성 제어 지연을 없애기 위해 사용된다.

## 연결 개념
- **006 연결 리스트**: 스택·큐·덱을 구현하는 기본 재료
- **010 그래프 탐색**: DFS는 스택(또는 재귀), BFS는 큐를 엔진으로 사용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 요소의 삽입(Push/Enqueue)과 삭제(Pop/Dequeue) 위치를 제한하여 데이터 처리 순서를 정책적으로 강제하는 추상 자료형(ADT)이다.
> 2. **가치**: 스택의 LIFO는 시스템 상태 복원에, 큐의 FIFO는 비동기 트래픽 버퍼링에 적용되어 시스템 신뢰성을 보장한다.
> 3. **판단 포인트**: 트래픽 폭증 시 큐의 Overflow 한계를 방어하기 위해 배열 기반의 환형 큐나 동적 확장이 가능한 연결 리스트 큐를 제약에 맞춰 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 제약적 선형 자료구조 목적 이해 | LIFO(Stack), FIFO(Queue) 정책 및 ADT 개념 | 단순 데이터 저장소로만 정의하는 오류 |
| 구조 간 차이와 실무 활용 도출 | 시스템 상태 복원(Stack) vs 비동기 버퍼링(Queue) | 3가지 구조의 차이점만 나열하고 활용 사례 생략 |

> 요약: 스택과 큐는 알고리즘 기초를 넘어, 스케줄링부터 대규모 분산 메시징까지 운영체제와 시스템의 코어 엔진이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터의 삽입과 삭제가 특정 양 끝단에서만 이루어지도록 입출력 규칙을 제한한 선형 추상 자료형
- 배경: 자유로운 배열 접근은 함수 호출 복원이나 작업 대기열 처리 시 데이터 무결성을 파괴하므로 제약 공간 필요
- 필요성: 시스템 부하 시 비동기 요청을 유실 없이 O(1) 단위로 버퍼링하고, 서브루틴 상태를 정확히 복귀시키기 위해 필수

---

## Ⅱ. 구조 및 구성요소

```text
[스택: LIFO]          [큐: FIFO]                  [덱: 양방향]
| Push | Pop ^       | Enqueue |   Dequeue ^     | Push/Pop |  | Push/Pop |
|  V   |     |       |    V    |      |          |   V  ^   |  |   V  ^   |
|--- Top ----|       |-- Rear --- Front -------| |- Front ------ Rear -|
```

| 구조명 | 제한 정책 | 주요 포인터 (인덱스) | 특이사항 |
|:---|:---|:---|:---|
| 스택 | LIFO (후입선출) | Top (최상단 위치) | 재귀(Recursion), 상태 복원 기반 |
| 큐 | FIFO (선입선출) | Front (출구), Rear (입구) | 생산자-소비자 패턴 버퍼링 핵심 |
| 덱 | 양방향 입출력 | Front, Rear 양쪽 갱신 | 스택과 큐의 성질을 런타임에 동시 지원 |

> 요약: 물리적 구현체(배열/리스트)와 무관하게 시스템 통제를 위해 강제된 입출력 인터페이스 규약이다.

---

## Ⅲ. 동작원리 및 큐 한계 극복 흐름도

```text
선형 큐 요소 반복 삭제 -> Front 이동 -> 앞쪽 공간 유휴 발생(가짜 Overflow) -> 환형 큐(Circular) 전환
```

- 1단계 [초기화]: Front와 Rear를 동일 인덱스로 설정하여 큐의 비어있음 선언
- 2단계 [삽입/Enqueue]: `Rear = (Rear + 1) % N` 연산을 통해 위치 이동 후 데이터 적재
- 3단계 [삭제/Dequeue]: `Front = (Front + 1) % N` 연산으로 가장 오래된 데이터 추출
- 4단계 [상태 검사]: `(Rear + 1) % N == Front` 시 오버플로우 차단 및 대기 처리

> 요약: 배열 기반 큐에서는 가짜 오버플로우로 인한 메모리 낭비를 막기 위해 나머지 연산(%) 기반의 환형 구조 로직이 필수적이다.

## Ⅳ. 특징

| 구분 | 배열 기반 구현 | 연결 리스트 기반 구현 | 판단 포인트 |
|:---|:---|:---|:---|
| 제약 사항 | 크기 고정 (Overflow 위험 내재) | 힙 메모리 고갈 전까지 무한 동적 확장 | 트래픽 최대치 예측 여부 |
| 성능 효율 | 연속 메모리 할당으로 캐시 적중률 우수 | 노드 파편화로 캐시 적중률 저하 | CPU 접근 속도 민감도 |
| 메모리 관리 | 인덱스 연산으로 재사용 (환형 로직 필요) | 잦은 동적 할당/해제에 따른 GC 부하 | 빠른 메모리 순환 요구 환경 |

> 요약: RTOS 임베디드 환경은 예측 가능한 배열 환형 큐를, 유동적인 웹 분산 시스템은 연결 리스트 큐를 표준으로 채택한다.

## Ⅴ. 심화 비교 및 파생 자료구조 적용 판단

| 파생 구조 | 파생 원리 | 해결 리스크 | 실무 적용처 |
|:---|:---|:---|:---|
| 우선순위 큐 | FIFO 파괴, Heap 정렬 기반 추출 | 중요도가 높은 우선 작업의 처리 지연 방지 | 프로세스 스케줄링 |
| 차단 큐(Blocking Q) | 포화/고갈 시 스레드 Sleep 대기 통제 | 멀티 스레드 간 데이터 레이스 방지 | Thread Pool 작업 분배 |
| 락 프리 큐 | 원자적 CAS 명령어 도입 | 락 점유로 인한 컨텍스트 스위칭 지연 제거 | 고성능 금융 거래 엔진 |

> 요약: 단일 스레드 구조의 기본 큐를 다중 스레드 환경으로 확장하기 위해 락킹(Locking) 전략과 정렬을 결합한다.

**리스크·대응:**
- 스택 오버플로우: 재귀 호출 프레임이 콜 스택 한계 초과 → 꼬리 재귀 최적화 또는 명시적 힙 스택 자료구조로 전환 (지표: 최대 재귀 깊이)
- 큐 포화 유실: 소비자 처리 속도보다 생산자 유입 속도가 빠름 → 백프레셔(Backpressure) 적용 및 Dead Letter Queue 처리 (지표: 큐 대기 길이)
- 기아(Starvation) 현상: 우선순위 큐에서 낮은 우선순위 작업 무한 대기 → 에이징(Aging) 기법으로 대기 시간에 비례해 우선순위 점진 상향 (지표: 최대 작업 대기 시간)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대규모 MSA 비동기 메시징 (Queue): Kafka, RabbitMQ 브로커를 도입하여 마이크로서비스 간 트래픽 스파이크를 큐에 버퍼링
2. 가상머신 생명주기 제어 (Stack): JVM 메모리의 Stack Area를 통해 메서드 호출 프레임 및 로컬 변수 생명주기 관리
3. 스케줄링 큐 최적화 (Deque): Work-Stealing 알고리즘 구현 시 자신의 덱 한쪽(LIFO)에서 작업을 빼고, 유휴 스레드는 반대쪽(FIFO)에서 획득

**결론 (2줄):**
- 기술사 판단: 스택과 큐는 시스템 아키텍처에서 비동기적 트래픽을 완충하고 호출 상태 무결성을 통제하는 기본 메커니즘이다.
- 향후 방향: 단일 노드의 자료구조 한계를 넘어 서버 간 상태 일관성을 동기화하는 분산 큐(Distributed Queue) 아키텍처로 진화하고 있다.
