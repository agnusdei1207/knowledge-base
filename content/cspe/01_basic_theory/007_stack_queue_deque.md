## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 데이터 삽입·삭제 방향에 따라 구분되는 선형 자료구조로, 스택(LIFO)·큐(FIFO)·덱(양방향)으로 분류됨 |
| **배경/필요성** | 함수 호출 관리(스택), 작업 대기열(큐), 양방향 캐시(덱) 등 자료 접근 패턴에 맞는 추상 자료형이 필요함 |
| **출제 의도** | 세 자료구조의 연산 특성과 활용 사례를 구분하고 구현 방식을 설명할 수 있는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|  스택    | --> |   큐     | --> |   덱     |
| (LIFO)  |     | (FIFO)   |     | (양방향) |
| push/pop|     | enq/deq  |     | 양끝연산  |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 스택(LIFO) | 한쪽 끝(Top)에서만 삽입·삭제하며, 마지막 삽입 원소가 먼저 나옴 | 접시 쌓기 |
| 큐(FIFO) | 뒤(Rear)에서 삽입, 앞(Front)에서 삭제하며, 먼저 삽입된 원소가 먼저 나옴 | 매표소 줄 |
| 덱(Deque) | 양쪽 끝에서 삽입·삭제가 가능한 일반화된 큐임 | 양방향 출입구 |

> 요약: 스택(LIFO)·큐(FIFO)·덱(양방향)은 삽입·삭제 방향에 따라 구분되는 O(1) 연산 자료구조임.

## Ⅲ. 절차
```
+------------+     +------------+
| push(data) | --> | Top 갱신   |
| (삽입)     |     | (Top+1)   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 반환       | <-- | pop()     |
| (Top 데이터)|    | Top 감소   |
+------------+     +------------+
```

1. 삽입(Push/Enqueue): 스택은 Top 위치에, 큐는 Rear 위치에 원소를 추가함
2. 포인터 갱신: 삽입 후 Top/Rear 인덱스를 증가시킴(원형 큐는 모듈러 연산)
3. 삭제(Pop/Dequeue): 스택은 Top에서, 큐는 Front에서 원소를 제거·반환함
4. 오버플로우/언더플로우 검사: 삽입 시 Full, 삭제 시 Empty 상태를 검사하여 예외 처리함

> 요약: 삽입 → 포인터 갱신 → 삭제 → 경계 검사로 O(1) 연산을 수행함.

## Ⅳ. 문제점
- 배열 기반 크기 고정: 정적 배열 구현 시 크기 초과 시 오버플로우가 발생함
- 선형 큐 공간 낭비: Dequeue 후 앞쪽 공간이 재사용되지 않아 메모리가 낭비됨
- 동시성 문제: 멀티 스레드 환경에서 Push/Pop 동시 접근 시 데이터 경합이 발생함

## Ⅴ. 개선방안
- (단기) 원형 큐: 배열을 원형으로 사용하여 앞쪽 빈 공간을 재활용함
- (중기) 동적 배열: ArrayList 기반으로 크기를 2배씩 확장하여 오버플로우를 방지함
- (장기) Lock-free 구현: CAS(Compare-And-Swap) 기반 Lock-free 큐로 동시성 성능을 확보함

## Ⅵ. 전망
- 메시지 큐(Kafka·RabbitMQ)·태스크 스케줄러·BFS 탐색 등에서 큐가 핵심 역할을 하며, 분산 환경의 Lock-free 동시성 큐가 고성능 시스템의 표준이 될 전망임
