## 미리 알고가기

- ADT: 구현 방식보다 연산과 동작 규칙을 먼저 정의하는 추상 자료형(Abstract Data Type, ADT)임
- LIFO: 마지막에 들어간 데이터가 먼저 나오는 후입선출(Last-In First-Out, LIFO) 규칙임
- FIFO: 먼저 들어간 데이터가 먼저 나오는 선입선출(First-In First-Out, FIFO) 규칙임
- Front/Rear: 큐와 덱에서 삭제·삽입이 일어나는 양 끝 위치임
- Overflow/Underflow: 저장 공간 초과 또는 빈 구조에서 삭제하는 오류 상태임

## Ⅰ. 개요

- **정의**: 스택·큐·덱은 삽입·삭제가 허용되는 위치를 기준으로 LIFO, FIFO, 양단 접근 순서를 통제하는 선형 추상 자료형임
- **배경/필요성**: 삽입·삭제 위치를 LIFO·FIFO·양단 중 무엇으로 통제하느냐가 같은 데이터의 처리 결과를 바꾸므로, 저장 방식이 아니라 연산 규칙이 구조 선택의 기준임.
- **비유**: 스택은 접시 더미, 큐는 매표소 줄, 덱은 양쪽 문으로 타고 내릴 수 있는 셔틀과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 선형 ADT 선택 기준 확인 | LIFO, FIFO, 양단 연산, 구현 방식, 예외 조건 | 스택/큐 혼동, 구현과 ADT 혼동 |

> 요약: 스택·큐·덱은 데이터를 어디에서 넣고 빼는지로 처리 순서를 보장하는 선형 ADT임.

## Ⅱ. 특징/비교

| 판단 기준 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 처리 규칙 | LIFO | FIFO | 양쪽 삽입·삭제 |
| 핵심 연산 | push, pop, peek | enqueue, dequeue, front | push/pop front, push/pop back |
| 대표 용도 | 함수 호출, 괄호 검사, DFS | 작업 스케줄링, BFS, 메시지 대기열 | 슬라이딩 윈도우, 양방향 탐색 |
| 구현 주의 | top 위치 관리 | front/rear 순환 관리 | 양 끝 인덱스와 용량 관리 |
| 선택 조건 | 최근 상태를 먼저 되돌릴 때 | 도착 순서를 공정하게 유지할 때 | 앞뒤 양쪽 접근이 모두 필요할 때 |

> 요약: 세 자료구조의 선택 기준은 성능보다 처리 순서 규칙이 문제 요구와 일치하는지임.

- 배열 구현은 연속 메모리로 인덱스 접근이 O(1)이지만 정해진 용량을 넘으면 재할당이 필요함
- 연결 리스트 구현은 원소 수에 맞춰 늘고 줄지만 노드마다 포인터 저장과 동적 할당 비용이 붙음
- 동시성 큐에서는 순서 보장뿐 아니라 생산자·소비자 경합과 메모리 가시성이 중요함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력연산 | ---> | ADT 규칙 | ---> | 출력연산 |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 저장공간 |      | 끝 포인터|      | 예외처리 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 저장 공간 | 배열, 순환 배열, 연결 리스트처럼 실제 데이터를 담는 구현 기반임 | 창고 |
| 위치 포인터 | top, front, rear처럼 삽입·삭제 기준 위치를 나타냄 | 입구 표지판 |
| 삽입 연산 | 규칙에 맞는 끝 위치에 새 원소를 추가함 | 줄에 서기 |
| 삭제 연산 | 규칙에 맞는 끝 위치에서 원소를 제거하고 반환함 | 차례대로 나가기 |
| 예외 조건 | 빈 구조 삭제, 꽉 찬 배열 삽입, 인덱스 래핑을 검증함 | 출입 통제 |

> 요약: 스택·큐·덱은 저장 공간 위에 위치 포인터와 삽입·삭제 규칙을 얹어 순서를 보장하는 구조임.

- 순환 큐는 배열 공간을 재사용하기 위해 front와 rear를 모듈러 연산으로 이동함
- 덱은 스택과 큐 기능을 모두 제공하지만, 문제에서 필요한 연산을 제한해야 의미가 명확해짐
- ADT는 외부 동작 계약이므로 내부 구현을 바꿔도 연산 의미는 유지되어야 함

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 요구확인 | ---> | 구조선택 | ---> | 연산수행 | ---> | 상태검증 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 순서규칙 |      | 구현선택 |      | push/pop |      | 예외/결과|
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 최근 데이터 우선, 도착 순서 유지, 양단 접근 중 어떤 순서 제약이 필요한지 확인함
2. **구조와 구현 선택** - 스택, 큐, 덱을 고르고 데이터 규모와 용량 변화에 따라 배열 또는 연결 리스트를 선택함
3. **핵심 연산 수행** - 삽입·삭제 위치 포인터를 갱신하며 규칙에 맞게 원소를 추가하거나 제거함
4. **검증/통제** - underflow, overflow, 순환 인덱스, 동시 접근 경합을 확인하고 결과를 반환함

> 요약: 절차는 처리 순서 요구를 ADT 규칙으로 바꾸고, 구현별 위치 포인터를 안전하게 갱신하는 흐름임.

- 깊이 우선 탐색(Depth-First Search, DFS)은 스택, 너비 우선 탐색(Breadth-First Search, BFS)은 큐로 탐색 순서가 결정되어 알고리즘 선택이 곧 ADT 선택임
- 고정 크기 배열에서는 예외 처리가 성능보다 먼저 확인되어야 함
- 다중 스레드 환경에서는 잠금 범위와 대기 정책이 처리량을 좌우함

## Ⅴ. 문제점

- **P1 잘못된 순서 모델 선택**: LIFO가 필요한 문제에 큐를 쓰거나 FIFO가 필요한 문제에 스택을 쓰면 알고리즘 결과 자체가 달라짐
- **P2 경계 상태 오류**: 빈 구조 삭제, 꽉 찬 배열 삽입, 순환 인덱스 래핑 실수로 데이터 손실이나 예외가 발생함
- **P3 동시성 경합**: 생산자·소비자가 동시에 접근하면 순서 보장, 원자성, 메모리 가시성 문제가 발생할 수 있음

> 요약: 스택·큐·덱의 운영 문제는 순서 규칙 선택, 경계 조건, 동시 접근 통제에서 주로 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 문제의 처리 순서를 먼저 상태 전이로 표현하고 DFS/BFS, undo/redo, 대기열 요구에 맞춰 ADT를 선택함 (확인: 대표 입력 결과)
- **P2 대응**: 빈/가득 참 조건을 명시하고 순환 배열의 한 칸 비움 또는 size 카운터 정책을 표준화함 (확인: 경계값 테스트)
- **P3 대응**: 단일 생산자·소비자, 다중 생산자·소비자 조건에 맞는 잠금 큐 또는 lock-free 큐를 선택함 (확인: 동시성 스트레스 테스트)

> 요약: 개선은 순서 요구를 명확히 하고 경계·동시성 규칙을 구현 계약으로 고정하는 방식이 필요함.

## Ⅶ. 전망

- **발전 방향**: 이벤트 기반 시스템, 스트리밍 처리, 병렬 런타임에서 큐와 덱은 스케줄링과 백프레셔 제어의 기본 구조로 계속 활용됨
- **기술사적 판단**: ADT 선택은 평균 복잡도보다 처리 순서, 경계 조건, 동시 접근 요구를 기준으로 판단해야 함
- **기술사 제언**: 답안에서는 세 자료구조를 한 표로 비교하고, 실제 적용 예시를 DFS·BFS·슬라이딩 윈도우와 연결하면 설명력이 높아짐
