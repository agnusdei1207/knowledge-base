## 미리 알고가기

- LIFO(Last-In, First-Out): 마지막 삽입 데이터가 먼저 제거되는 후입선출 원리임
- FIFO(First-In, First-Out): 먼저 삽입된 데이터가 먼저 제거되는 선입선출 원리임
- Deque(Double-Ended Queue): $Front$와 $Rear$ 양쪽에서 삽입·삭제하는 구조임
- 오버플로(Overflow): 가득 찬 저장체에 삽입을 요청한 상태임
- 언더플로(Underflow): 비어 있는 저장체에 삭제를 요청한 상태임

## Ⅰ. 개요

- **정의/개념**: 스택·큐·덱은 삽입·삭제 끝점을 제한해 처리 순서를 제어하는 선형 자료형임
- **배경/필요성**: 호출 이력, 작업 대기열, 버퍼링은 유입 순서가 결과를 바꾸므로 임의 접근보다 입출력 규칙이 필요함

## Ⅱ. 특징

- 접근 끝점을 제한해 탐색·스케줄링·버퍼링 순서를 통제함
- 스택은 역순, 큐는 도착순, 덱은 양방향 처리를 보장함
- 끝점 포인터 갱신만으로 삽입·삭제 $O(1)$을 구현함
- 배열·연결 리스트 구현에 따라 경계 오류 관리 방식이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| **처리 순서** | $LIFO$ | $FIFO$ | 양방향 입출력 |
| **접근 끝점** | $Top$ 한쪽 | $Rear$ 삽입, $Front$ 삭제 | $Front$, $Rear$ 모두 |
| **주요 활용** | 재귀 호출, 괄호 검사, DFS | 스케줄링, 버퍼, BFS | 슬라이딩 윈도우, 0-1 BFS, 양방향 탐색 |
| **보장 조건** | $Top$ 경계 관리 | 원형 인덱스 또는 링크 관리 | 양끝 포인터 정합성 |
| **시간복잡도** | 삽입·삭제 $O(1)$ | 삽입·삭제 $O(1)$ | 양끝 삽입·삭제 $O(1)$ |

> 요약: 작업의 역순 처리가 필요하면 스택을, 유입 순서대로 처리가 필요하면 큐를, 양방향 제어가 필요하면 덱을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 저장체 | 데이터를 담는 배열 또는 연결 리스트 구조임 |
| 제어 포인터 | $Top$, $Front$, $Rear$처럼 입출력 위치를 나타내는 변수임 |
| 상태 판정 | $Empty$와 $Full$을 검사해 언더플로·오버플로를 막음 |
| 입출력 연산 | $Push/Pop$, $Enqueue/Dequeue$, 양끝 삽입·삭제를 수행함 |

```text
[ 선형 자료구조 입출력 모델 ]
Stack:        Top -> [D3] -> [D2] -> [D1]
Queue:  Front [D1] -> [D2] -> [D3] Rear
Deque:  Front <-> [D1] <-> [D2] <-> Rear
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 연산 요청    | --> | 상태 검사    | --> | 데이터 처리  | --> | 포인터 갱신  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **연산 요청**: 삽입($Push/Enqueue$) 또는 삭제($Pop/Dequeue$)를 받음
2. **상태 검사**: 삽입 전 $Full$, 삭제 전 $Empty$ 여부를 확인함
3. **데이터 처리**: 현재 포인터 위치에 데이터를 쓰거나 읽어 반환함
4. **포인터 갱신**: $Top$, $Front$, $Rear$를 이동함

## Ⅵ. 실무 적용 및 유의점

1. DFS·재귀는 깊은 입력에서 명시적 스택으로 전환하고 최대 깊이와 메모리로 확인함
2. 배열 큐는 원형 큐로 이동 비용을 없애고 공백·포화 경계 테스트로 확인함

## Ⅶ. 결론

- 스택·큐·덱은 처리 순서와 접근 끝점으로 선택하고 $O(1)$ 조건·경계 오류를 검증함
