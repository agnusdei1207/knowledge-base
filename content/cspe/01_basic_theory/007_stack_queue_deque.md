# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 스택·큐·덱은 **삽입·삭제가 일어나는 위치를 규칙으로 제한**한 선형 자료구조로, 스택은 한쪽 끝만(LIFO), 큐는 양끝을 넣는 곳·빼는 곳으로 나눠(FIFO), 덱은 양끝 모두 허용한다.
- **왜 필요한가**: 연결 리스트·배열(006 참조)은 어디든 넣고 뺄 수 있어 자유롭지만, "가장 최근 것부터" 혹은 "먼저 온 것부터"처럼 **처리 순서 자체가 규칙인 문제**에서는 위치를 제한해야 로직이 단순·안전해지기 때문이다.
- **핵심 직관**: 스택은 "책 쌓기"(맨 위만 넣고 뺌), 큐는 "매표소 줄"(뒤로 서고 앞에서 나감), 덱은 "양쪽 문이 다 열린 통로"(앞뒤 어디든 출입).

## 핵심 용어 정리 (내부에 등장하는 것들)

삽입·삭제 위치를 어떻게 제한하느냐가 세 구조를 가르는 핵심이다. 여기서 관련 용어를 먼저 세운다. 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 추상 자료형(ADT, 상위 키워드) | 동작(연산) 규칙만 정의하고 구현은 감춘 자료구조 | "넣고 뺀다"는 규칙만 약속, 속은 배열이든 리스트든 무방 |
| LIFO (Last In First Out) | 마지막에 넣은 것이 먼저 나오는 후입선출 | 접시 쌓기 — 맨 위 접시부터 집음 |
| FIFO (First In First Out) | 먼저 넣은 것이 먼저 나오는 선입선출 | 매표소 줄 — 앞사람부터 표를 삼 |
| Push / Pop | 스택의 삽입 / 삭제 연산(둘 다 top에서) | 책 올리기 / 맨 위 책 빼기 |
| Enqueue / Dequeue | 큐의 삽입(rear) / 삭제(front) 연산 | 줄 뒤에 서기 / 줄 앞에서 나가기 |
| Top | 스택에서 마지막에 넣은, 다음에 나올 위치 | 쌓인 책 더미의 맨 위 |
| Front / Rear | 큐에서 빼는 쪽(앞) / 넣는 쪽(뒤) | 줄의 맨 앞 / 맨 뒤 |
| 덱(Deque, Double-Ended Queue) | 양쪽 끝 모두에서 삽입·삭제 가능한 구조 | 양문 통로 — 앞뒤로 다 드나듦 |
| 원형 큐(Circular Queue) | 배열의 끝과 앞을 이어 빈 앞 공간을 재사용하는 큐 | 원형 컨베이어 — 한 바퀴 돌아 재사용 |
| 오버플로/언더플로 | 꽉 찬 곳에 push / 빈 곳에서 pop 하는 오류 | 다 찬 주차장 진입 / 빈 지갑에서 인출 |

## 깊이 이해
- **배경·문제의식**: 함수 호출 복귀, 실행 취소(Undo), 작업 대기열처럼 "순서가 규칙인" 문제가 많다. 이때 임의 위치 삽입을 허용하면 규칙이 깨지고 버그가 는다. 그래서 **연산 위치를 아예 구조로 못 박아** 규칙 위반을 원천 차단한 것이 이 세 ADT다.
- **작동 원리 (어떻게+왜)**:
  - 스택: top 하나만 움직인다. push는 top을 올리며 저장, pop은 top 값을 꺼내며 내린다 — 접근 지점이 하나뿐이라 push/pop 모두 O(1)이다.
  - 큐: front·rear 두 지표를 쓴다. rear에서 넣고 front에서 뺀다. 배열로 단순 구현하면 front가 전진하며 앞 공간이 버려지므로, **원형 큐**로 끝과 앞을 이어 그 공간을 재사용한다.
  - 덱: 양끝(front·rear) 모두에서 삽입·삭제를 허용해 스택·큐를 모두 흉내 낼 수 있다. 보통 이중 연결 리스트나 원형 배열로 구현한다.
- **비유**: 스택은 프링글스 통(마지막에 넣은 칩부터 꺼냄), 큐는 은행 번호표 줄, 덱은 양쪽에서 카드를 뽑고 넣을 수 있는 카드 덱.
- **구체 예시(수치·사례)**: 웹 브라우저 뒤로가기는 스택 — 방문 페이지를 push하고 뒤로가기로 pop한다. 프린터 인쇄 대기열은 큐 — 먼저 보낸 문서부터 출력한다. 슬라이딩 윈도우 최댓값 알고리즘은 덱으로 양끝을 조작해 O(N)에 처리한다. 세 구조 모두 핵심 연산은 O(1)이다(O(1) 의미는 001·002 참조).
- **흔한 오해·주의점**:
  - **스택·큐는 "구현"이 아니라 "규칙(ADT)"이다.** 내부는 배열로도, 연결 리스트(006)로도 만들 수 있다. LIFO/FIFO라는 동작 계약이 본질이다.
  - 배열 큐를 원형으로 만들지 않으면 front가 전진한 만큼 앞 공간을 못 쓰는 "가짜 포화"가 생긴다.
  - 덱은 양끝만 O(1)이고 **가운데 삽입·삭제·임의 접근은 지원하지 않거나 O(N)**이다.

## 연결 개념
- **연결 리스트 (006)**: 이 세 구조의 대표적 내부 구현 기반(포인터 기반 삽입·삭제).
- **트리 순회·그래프 탐색 (009·010)**: DFS는 스택(재귀 콜 스택 포함), BFS는 큐를 뼈대로 사용.
- **함수 호출 스택**: 재귀·서브루틴 복귀 주소 관리에 스택이 시스템 차원에서 쓰임.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 스택·큐·덱은 삽입·삭제 위치를 각각 한쪽(LIFO)·양끝 분리(FIFO)·양끝 허용으로 제한한 선형 ADT임.
> 2. **가치**: 처리 순서가 곧 규칙인 문제(복귀·대기열·탐색)에서 O(1) 연산으로 순서 무결성을 구조적으로 보장함.
> 3. **판단 포인트**: "최근 것 우선"이면 스택, "먼저 온 것 우선"이면 큐, 양쪽 접근이 필요하면 덱을 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LIFO·FIFO 규칙 이해 | 삽입·삭제 위치 제한과 top·front·rear 지표 | 스택·큐를 특정 구현(배열)으로 단정 |
| 원형 큐 필요성 파악 | 배열 큐의 앞 공간 낭비와 재사용 원리 | 원형 큐 미도입 시 가짜 포화 누락 |
| 실무 적용 판단 | 브라우저·대기열·탐색 등 순서 규칙 매핑 | 세 구조 용도 혼동, 덱 중간 접근 가정 |

> 요약: 세 구조는 연산 위치 제한 규칙(ADT)이며, 원형 큐 재사용과 순서별 용도 매핑까지 함께 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 삽입·삭제 위치를 규칙으로 제한한 선형 자료구조(스택·큐·덱)의 총칭임
- 배경: 순서가 곧 처리 규칙인 문제에서 임의 위치 삽입은 규칙 위반·버그를 유발함
- 필요성: 함수 복귀·작업 대기·탐색 순서를 O(1) 연산으로 무결하게 보장할 구조가 필요함

## Ⅱ. 구조 및 구성요소
선형 구조도 (연산 위치 제한):

    스택(LIFO) : 입력 -> [ ..., top] <- push/pop (한쪽 끝만)
    큐(FIFO)   : enqueue -> [rear ... front] -> dequeue (양끝 분리)
                 / 원형 큐 : 배열 끝과 앞을 연결해 front 전진분 재사용
    덱(Deque)  : 삽입/삭제 <- [front ... rear] -> 삽입/삭제 (양끝 모두)

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Top (스택) | push·pop이 일어나는 단일 접근점 | 접근점 1개라 O(1) |
| Front / Rear (큐) | 삭제 지점 / 삽입 지점 분리 | 두 지표로 선입선출 유지 |
| 원형 배열/버퍼 | front 전진으로 빈 앞 공간 재사용 | 포화·공백 판별에 여분 칸·카운터 사용 |
| 양끝 포인터 (덱) | 앞·뒤 각각의 삽입·삭제 지점 | 이중 연결 리스트로 흔히 구현 |

> 요약: 스택은 top 하나, 큐는 front·rear 둘, 덱은 양끝을 접근점으로 두며 원형 구조로 배열 공간을 재활용함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (큐 원형 재사용):

    enqueue: rear = (rear+1) mod 크기 -> 값 저장 -> count 증가
    dequeue: front 값 반환 -> front = (front+1) mod 크기 -> count 감소

1. 스택 push/pop: 응용이 top 위치에 값을 저장·회수하고 top 지표를 올리거나 내림(O(1))
2. 큐 enqueue/dequeue: 생산자가 rear에 넣고 소비자가 front에서 빼며, 모듈러 연산으로 인덱스를 원형 순환시킴
3. 포화·공백 판별: 시스템이 count(또는 여분 칸)로 오버플로(꽉 참에 push)·언더플로(빈 곳 pop)를 사전 차단함
4. 덱 조작: 응용이 front·rear 양끝 중 필요한 쪽에서 삽입·삭제해 스택·큐 동작을 겸함

> 요약: 스택은 top 단일 지표, 큐는 front·rear를 모듈러로 순환시키며, count로 포화·공백을 판별해 오류를 막음.

## Ⅳ. 특징
- 연산 위치 제한: 삽입·삭제 지점을 구조로 못 박아 순서 규칙 위반을 원천 차단함
- 상수 시간 연산: 핵심 삽입·삭제(push/pop·enqueue/dequeue)가 모두 O(1)임
- 임의 접근 불가: 인덱스로 K번째에 직접 못 가며 규칙에 맞는 끝단만 접근 가능함
- 구현 독립성: 동일 ADT를 배열·연결 리스트 어느 쪽으로도 구현할 수 있음
- 덱의 겸용성: 양끝 허용으로 스택·큐 동작을 하나의 구조로 대체 가능함

## Ⅴ. 심화 비교 및 적용 판단

삽입·삭제 위치와 대표 용도 축에서 세 구조를 대조함.

| 구분 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| 처리 순서 | LIFO(후입선출) | FIFO(선입선출) | 양끝 자유(혼합) |
| 삽입/삭제 위치 | top 한쪽 끝 | rear 삽입 / front 삭제 | front·rear 양끝 |
| 핵심 연산 복잡도 | push·pop O(1) | enqueue·dequeue O(1) | 양끝 삽입·삭제 O(1) |
| 대표 용도 | 함수 복귀·Undo·DFS | 작업 대기열·BFS·버퍼 | 슬라이딩 윈도우·양방향 큐 |

> 요약: "최근 우선"은 스택, "먼저 온 것 우선"은 큐, 양쪽 접근이 필요하면 덱이며 셋 다 끝단 연산은 O(1)임.

**리스크·대응:**
- 스택 오버플로 — 재귀 깊이·push 폭주로 콜 스택 초과 → 반복문 전환·최대 깊이 제한
- 큐 앞 공간 낭비 — 배열 큐 front 전진으로 가짜 포화 → 원형 큐(모듈러 인덱스) 적용
- 언더플로 — 빈 구조에서 pop/dequeue → 연산 전 공백 검사·예외 처리 강제

**점검 지표:**
- 성능: 큐 대기열 길이·처리 지연 — 생산자·소비자 처리량 실측
- 안정성: 오버플로·언더플로 발생률 — 경계 조건 단위 테스트

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 메시지 큐(Kafka·RabbitMQ)로 생산자-소비자를 FIFO 큐로 비동기 분리해 트래픽 버퍼링·부하 평준화 구현
2. 실행 취소(Undo/Redo)를 두 개의 스택으로 구성해 최근 작업부터 O(1)에 되돌림
3. 링 버퍼(원형 큐)를 네트워크 패킷·오디오 스트림 버퍼로 사용해 고정 메모리로 연속 스트림 처리

**결론:**
- 기술사 판단: 순서가 "최근 우선"이면 스택, "도착 순"이면 큐를 택하되, 양방향 접근이 필요하면 덱으로 통합하는 조건부 선택이 유효함
- 향후 방향: 분산 환경에서 인메모리 큐(Redis Stream)·메시지 브로커가 마이크로서비스 간 비동기 결합 해소의 핵심 기반으로 확대되는 추세임
