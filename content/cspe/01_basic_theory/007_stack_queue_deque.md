## 미리 알고가기

- LIFO(Last-In, First-Out): 마지막에 삽입된 데이터가 가장 먼저 제거되는 후입선출 원리임
- FIFO(First-In, First-Out): 가장 먼저 삽입된 데이터가 가장 먼저 제거되는 선입선출 원리임
- Deque(Double-Ended Queue): 양쪽 끝(Front, Rear) 모두에서 삽입과 삭제가 가능한 선형 자료구조임
- 오버플로(Overflow): 저장 공간이 가득 찬 상태에서 데이터를 추가로 삽입하려 할 때 발생하는 오류임
- 언더플로(Underflow): 저장된 데이터가 없는 상태에서 삭제를 요청할 때 발생하는 오류임

## Ⅰ. 개요

- **정의/개념**: 스택, 큐, 덱은 데이터 삽입·삭제가 허용되는 끝점을 제한해 처리 순서(Order)를 제어하는 선형 추상 자료형임
- **배경/필요성**: 함수 실행 이력 관리, 작업 대기열 처리, 메시지 버퍼링 등 데이터의 유입 순서가 처리 결과의 정합성을 결정하는 문제에서는 임의 접근보다 엄격한 입출력 규칙을 강제할 구조가 필요함

## Ⅱ. 특징

- 입출력 위치를 제한해 탐색·스케줄링·버퍼링에서 처리 순서를 명시적으로 통제함
- 포인터 또는 인덱스 갱신만으로 삽입·삭제를 처리하므로 적절한 구현에서는 상수 시간 연산을 기대할 수 있음
- 저장 방식이 배열인지 연결 리스트인지에 따라 오버플로, 언더플로, 포인터 경계 오류의 관리 방식이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| **입출력 원리** | $LIFO$ (후입선출) | $FIFO$ (선입선출) | 양방향 선택 가능 |
| **삽입/삭제 위치** | 한쪽 끝 ($Top$) | $Rear$ 삽입 / $Front$ 삭제 | $Front$, $Rear$ 양쪽 모두 |
| **주요 활용** | 재귀 호출, 괄호 검사, DFS | 스케줄링, 버퍼, BFS | 슬라이딩 윈도우, 0-1 BFS, 양방향 탐색 |
| **시간복잡도** | 삽입·삭제 $O(1)$ | 원형 배열 또는 연결 리스트 기준 삽입·삭제 $O(1)$ | 삽입·삭제 $O(1)$ |

> 요약: 작업의 역순 처리가 필요하면 스택을, 유입 순서대로 처리가 필요하면 큐를, 양방향 제어가 필요하면 덱을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 저장체 | 데이터를 실제로 담는 배열(Array) 또는 연결 리스트(Linked List) 구조임 |
| 제어 포인터 | 데이터가 들어오고 나가는 위치를 가리키는 $Top$, $Front$, $Rear$ 등의 변수임 |
| 상태 판정 로직 | 현재 공간이 비어있는지($Empty$) 혹은 가득 찼는지($Full$) 확인하여 예외를 방어함 |
| 입출력 연산 | $Push/Pop$, $Enqueue/Dequeue$, 양끝 삽입·삭제처럼 구조별 접근 규칙을 구현하는 명령임 |

```text
[ 선형 자료구조 입출력 모델 ]
Stack:   [Data3] (Top) -> [Data2] -> [Data1]  (한 방향)
Queue:   [Data3] (Rear) -> [Data2] -> [Data1] (Front) (통로형)
Deque:   (Front) <-> [Data1] <-> [Data2] <-> (Rear)   (양방향)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 연산 요청    | --> | 용량/상태 체크 | --> | 데이터 입출력 | --> | 포인터 업데이트|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **연산 요청** — 외부 인터페이스를 통해 삽입($Push/Enqueue$) 또는 삭제($Pop/Dequeue$) 요청을 수신함
2. **상태 체크** — 삽입 시에는 가득 찼는지($Full$), 삭제 시에는 비었는지($Empty$)를 먼저 판정하여 오버플로/언더플로를 방지함
3. **입출력 수행** — 현재 포인터가 가리키는 메모리 위치에 데이터를 쓰거나, 해당 위치의 데이터를 읽어 반환함
4. **포인터 갱신** — 연산이 성공하면 $Top$을 증감시키고, 원형 큐와 덱은 요청된 끝점에 따라 $Front$ 또는 $Rear$를 이동함

## Ⅵ. 실무 적용 및 유의점

1. 재귀 호출이나 DFS처럼 스택 사용량이 커지는 작업은 호출 깊이 한계와 스택 메모리 사용량을 확인하고, 초과 가능성이 있으면 반복문 기반 명시적 스택으로 전환해야 함
2. 단순 배열 큐에서 삭제마다 원소를 이동하면 지연이 커지므로 원형 큐로 포인터만 이동시키고, 큐 길이와 공백·포화 경계 테스트로 정상 동작을 확인해야 함

## Ⅶ. 결론

- 스택·큐·덱은 처리 순서와 접근 끝점을 기준으로 선택하는 기초 자료구조이므로, 구현 시 저장 방식별 $O(1)$ 보장 조건과 오버플로·언더플로·$Off-by-one$ 경계를 함께 검증해야 함
