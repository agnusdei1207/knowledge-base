## 미리 알고가기

- ADT: 구현 방법보다 허용 연산과 동작 규칙을 정의하는 추상 자료형임
- LIFO: 마지막에 들어온 데이터가 먼저 나가는 규칙임
- FIFO: 먼저 들어온 데이터가 먼저 나가는 규칙임

## Ⅰ. 개요

- **정의**: 삽입·삭제 위치 규칙으로 구분되는 선형 추상 자료형임
- **배경/필요성**: 함수 호출, 작업 대기열, 캐시 관리처럼 데이터 처리 순서가 결과와 성능을 좌우하는 경우 접근 규칙을 자료구조로 고정해야 함
- **비유**: 스택은 접시 더미, 큐는 대기줄, 덱은 양쪽 문이 있는 줄임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 선형 자료구조의 접근 규칙과 활용 구분 | LIFO, FIFO, 양방향 삽입·삭제, overflow/underflow | 스택·큐 활용 혼동, 예외 처리 누락 |

> 요약: 스택·큐·덱은 저장 구조보다 "어느 끝에서 넣고 빼는가"가 핵심인 자료구조임.

## Ⅱ. 특징/비교

| 판단 기준 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 접근 규칙 | LIFO | FIFO | 양끝 삽입·삭제 |
| 대표 연산 | `push`, `pop`, `top` | `enqueue`, `dequeue`, `front` | `push_front/back`, `pop_front/back` |
| 주요 활용 | 호출 스택, DFS, undo | 작업 대기열, BFS, 버퍼 | 슬라이딩 윈도우, LRU, 양방향 큐 |

> 요약: 세 구조는 같은 선형 자료라도 제거 순서가 달라 적용 문제가 달라짐.

- 배열 구현은 인덱스 접근과 캐시 지역성이 좋지만 크기 제한과 원형 버퍼 처리가 필요함
- 연결 리스트 구현은 크기 변경이 쉽지만 포인터 비용과 캐시 미스가 증가함
- 동시성 환경에서는 단일 큐 락이 병목이 될 수 있어 lock-free 또는 분할 큐가 필요할 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력연산 | ---> | 저장영역 | ---> | 출력연산 |
| push/enq |      | array/list|     | pop/deq  |
+----------+      +----------+      +----------+
                         |
                         v
                   +----------+
                   | 상태검사 |
                   +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 저장 영역 | 배열, 연결 리스트, 원형 버퍼 등 실제 데이터를 담는 공간임 | 줄을 세우는 공간 |
| 삽입 포인터 | 새 데이터가 들어갈 위치를 가리키는 인덱스 또는 참조임 | 입구 표시 |
| 삭제 포인터 | 다음으로 제거될 데이터 위치를 가리키는 인덱스 또는 참조임 | 출구 표시 |
| 상태 검사 | 비어 있음, 가득 참, 크기, 경계 조건을 확인함 | 입장 가능 여부 확인 |

> 요약: 스택·큐·덱은 저장 영역과 양끝 포인터, 상태 검사로 접근 규칙을 구현함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 연산요청 | ---> | 상태검사 | ---> | 포인터갱신 | ---> | 결과반환 |
+----------+      +----------+      +----------+      +----------+
```

1. **연산 요청**: `push`, `pop`, `enqueue`, `dequeue` 등 요청 연산을 식별함
2. **상태 검사**: 빈 구조에서 삭제하거나 고정 크기 구조가 가득 찬 상태인지 확인함
3. **포인터 갱신**: 접근 규칙에 맞게 top, front, rear, 양끝 인덱스를 이동함
4. **결과 반환**: 삽입 성공, 제거 원소, 예외 상태를 반환함

> 요약: 선형 ADT 연산은 상태를 확인한 뒤 정해진 끝의 포인터만 갱신하는 과정임.

## Ⅴ. 문제점

- **P1 overflow/underflow**: 고정 크기 배열에서 가득 찬 상태에 삽입하거나 빈 상태에서 삭제하면 데이터 손실 또는 예외가 발생함
- **P2 동시성 경쟁**: 다중 생산자·소비자가 같은 큐를 갱신하면 락 경합, 순서 뒤섞임, ABA 문제가 발생할 수 있음
- **P3 접근 규칙 오용**: BFS에 스택을 쓰거나 undo에 큐를 쓰면 알고리즘 의미가 바뀌어 결과가 틀어짐

> 요약: 스택·큐·덱 오류는 경계 상태, 동시 갱신, 접근 규칙 선택에서 주로 발생함.

## Ⅵ. 개선방안

1. **단기**: 빈 상태·가득 찬 상태·단일 원소 상태를 테스트 케이스로 고정함
2. **중기**: 원형 버퍼, 동적 확장 배열, 예외 반환 규칙을 표준 구현으로 관리함
3. **장기**: 고성능 동시 큐는 lock-free, MPSC/MPMC 큐, backpressure 정책으로 설계함

- **P1 대응**: 경계 검사와 용량 정책을 명시함 (확인: overflow/underflow 테스트)
- **P2 대응**: 동시성 모델에 맞는 큐 구현과 메모리 순서 규칙을 적용함 (확인: 경합 테스트, 순서 보장)
- **P3 대응**: 알고리즘별 접근 규칙을 설계 문서에 연결함 (확인: BFS/DFS 결과 검증)

> 요약: 선형 ADT 개선은 경계 처리, 동시성, 알고리즘 의미를 함께 관리하는 데 있음.

## Ⅶ. 전망

- 이벤트 기반 시스템, 메시지 큐, 스트리밍 처리에서 FIFO와 backpressure 설계의 중요성이 커짐
- 브라우저·편집기·캐시 시스템에서는 스택과 덱이 사용자 행동 복원과 최근성 관리의 기본 구조로 유지됨
- 기술사는 자료구조 이름보다 접근 규칙이 요구사항의 처리 순서와 맞는지 판단해야 함
