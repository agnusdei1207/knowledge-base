## 미리 알고가기

- $LIFO$: 마지막에 넣은 데이터를 먼저 꺼내는 규칙임
- $FIFO$: 먼저 넣은 데이터를 먼저 꺼내는 규칙임
- 덱($Deque$): 앞과 뒤 양쪽에서 삽입과 삭제가 가능한 구조임
- 원형 큐: 배열 끝에 도달하면 앞쪽 빈 공간을 다시 쓰는 큐 구현 방식임

## Ⅰ. 개요

- **정의/개념**: 스택, 큐, 덱은 데이터를 넣고 빼는 위치를 제한해 처리 순서를 보장하는 선형 자료구조임
- **배경/필요성**: 함수 호출, 작업 대기열, 버퍼는 처리 순서가 결과를 바꿈. 이런 문제에서는 임의 접근보다 삽입·삭제 규칙이 중요함

## Ⅱ. 특징

- 스택은 직전 상태를 먼저 꺼내므로 되돌리기와 재귀 처리에 맞음
- 큐는 도착 순서를 유지하므로 작업 대기열과 메시지 처리에 맞음
- 덱은 양쪽 끝을 모두 쓰므로 슬라이딩 윈도우나 양방향 작업열에 유연함
- 세 구조는 저장 방식보다 꺼내는 순서가 선택 기준이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 처리 순서 | $LIFO$ | $FIFO$ | 양쪽 끝 선택 |
| 삽입·삭제 위치 | 한쪽 끝 | 뒤에서 넣고 앞에서 뺌 | 앞과 뒤 |
| 대표 용도 | 함수 호출, 실행 취소, 괄호 검사 | 작업 대기열, 버퍼, 메시지 큐 | 슬라이딩 윈도우, 양방향 탐색 |
| 주의할 점 | 깊이가 커지면 스택 공간이 커짐 | 포화와 공백 조건을 구분해야 함 | 양쪽 포인터 갱신 오류를 조심해야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 저장 공간 | 배열이나 연결 구조로 원소를 보관함 |
| 입출력 포인터 | $top$, $front$, $rear$ 등 삽입·삭제 위치를 가리킴 |
| 공백 조건 | 꺼낼 원소가 없는 상태를 판정하는 규칙임 |
| 포화 조건 | 더 넣을 공간이 없는 상태를 판정하는 규칙임 |

```text
Stack: push/pop 한쪽 끝
Queue: rear 삽입 -> front 삭제
Deque: front/rear 양쪽 삽입·삭제
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 연산 요청 | --> | 상태 확인 | --> | 포인터 갱신 | --> | 원소 처리 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 삽입인지 삭제인지 확인함
2. 공백 또는 포화 상태를 먼저 판정함
3. 구조의 규칙에 맞게 포인터를 갱신함
4. 원소를 저장하거나 반환함

## Ⅵ. 실무 적용 및 유의점

1. 작업 처리 순서가 결과를 바꾸는 시스템에서는 $LIFO$와 $FIFO$ 중 어떤 규칙이 업무 의미와 맞는지 먼저 정해야 함
2. 배열 기반 큐와 덱은 포인터가 경계를 넘기 쉬우므로 빈 상태, 가득 찬 상태, 한 칸 남은 상태를 테스트해야 함

## Ⅶ. 결론

- 스택, 큐, 덱은 처리 순서를 보장하는 구조이며, 선택 기준은 저장 방식보다 어느 순서로 꺼내야 하는지에 있음
