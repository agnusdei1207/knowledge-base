# 📖 【암기용】 개념 완전 이해

> 목적: 스택·큐·덱을 단순 암기가 아니라 접근 제한 규칙과 시스템 적용 관점에서 이해하게 만든다.

## 한눈에
- **개요**: 삽입·삭제 가능한 끝을 제한해 데이터 처리 순서를 통제하는 선형 ADT
- **왜 필요한가**: 함수 호출, 작업 대기열, 슬라이딩 윈도우처럼 순서 규칙이 결과 정확도를 좌우하는 문제를 표현함
- **핵심 직관**: 스택은 접시 쌓기(LIFO), 큐는 은행 대기줄(FIFO), 덱은 양쪽 출입문이 있는 대기열임

## 깊이 이해
- **배경·문제의식**: 배열·연결 리스트는 저장 방법이고, 스택·큐·덱은 사용 규칙임. 같은 배열로도 top/front/rear 관리 방식에 따라 ADT가 달라짐
- **작동 원리**: 스택은 한쪽 끝 top에서 push/pop 수행, 큐는 rear 삽입·front 삭제, 덱은 front/rear 양쪽 삽입·삭제를 허용함
- **비유**: 브라우저 뒤로가기는 마지막 방문부터 되돌리는 스택, 프린터 작업은 먼저 들어온 문서부터 처리하는 큐, 작업 스케줄러는 앞뒤 우선순위를 조정하는 덱과 같음
- **구체 예시**: 원형 큐 크기 8에서 front=2, rear=6이면 원소 수는 (6-2+8)%8=4, 포화 판정은 (rear+1)%8 == front 사용
- **흔한 오해·주의점**: 큐를 선형 배열로 구현해 dequeue마다 왼쪽 이동하면 O(n) 비용이 발생함. 원형 큐 인덱스로 O(1)을 유지해야 함

## 연결 개념
- 연결 리스트 — 동적 크기 스택·큐 구현
- BFS — 큐로 레벨 순회 구현
- DFS·재귀 — 스택 또는 호출 스택으로 구현

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 스택·큐·덱은 저장소가 아니라 삽입·삭제 위치 제약으로 순서를 보장하는 추상 자료형이다.
> 2. **가치**: push/pop, enqueue/dequeue, 양단 연산을 배열 또는 연결 리스트로 구현하면 기본 연산을 O(1)로 처리할 수 있다.
> 3. **판단 포인트**: LIFO는 스택, FIFO는 큐, 양단 우선순위 조정은 덱을 선택한다.

---

## Ⅰ. 개요 및 필요성

스택·큐·덱은 데이터 처리 순서를 제한하는 선형 ADT이다. 시스템은 호출 복귀, 메시지 처리, 그래프 탐색처럼 순서가 바뀌면 결과가 달라지는 연산을 가진다. 따라서 ADT의 접근 규칙과 구현 복잡도를 함께 판단해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Stack:  [bottom] [  ] [top]       push/pop at top
Queue:  front -> [A][B][C] -> rear enqueue rear, dequeue front
Deque:  front <-> [A][B][C] <-> rear both ends
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Stack Top | 마지막 원소 위치 | push/pop O(1) |
| Queue Front/Rear | 삭제·삽입 위치 | 원형 큐로 이동 비용 제거 |
| Deque Ends | 양쪽 끝 포인터 | 양단 삽입·삭제 O(1) |
| Overflow/Underflow | 용량·공백 예외 | 배열 구현 시 경계 검사 필수 |

> 요약: 세 ADT는 같은 선형 저장소를 쓰더라도 허용되는 삽입·삭제 끝이 달라 처리 순서가 달라진다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 수신 -> ADT 유형 판정 -> 경계 검사 -> 포인터 이동 -> 원소 반환/저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 연산 요청 식별 | push/pop/enqueue/dequeue 구분 |
| 2 | Empty/Full 검사 | size==0, size==capacity |
| 3 | 인덱스·포인터 이동 | 원형 큐는 (idx+1)%N |
| 4 | 원소 저장·반환 | size ±1, 순서 규칙 보존 |

> 요약: ADT 연산은 경계 조건을 먼저 검사한 뒤 top/front/rear를 O(1)로 갱신해 순서를 보장한다.

---

## Ⅳ. 특징

| 구분 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 순서 규칙 | LIFO | FIFO | 양단 삽입·삭제 |
| 대표 연산 | push, pop, peek | enqueue, dequeue | addFirst, addLast, pollFirst |
| 시간복잡도 | O(1) | O(1) 원형 큐 기준 | O(1) |
| 적용 사례 | 재귀, undo, 괄호 검사 | BFS, 메시지 큐, 프린터 | 슬라이딩 윈도우, 작업 스케줄링 |

> 요약: 스택은 최근 작업 복귀, 큐는 도착 순서 처리, 덱은 양단 제어가 필요한 윈도우·스케줄링에 적용한다.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 호출·트랜잭션 롤백: 스택으로 undo 로그 저장, pop 순서로 역연산 수행
2. 비동기 처리: 큐에 메시지 적재, consumer 수 1~N개로 처리량 조절, 중복 처리는 idempotency key 적용
3. 윈도우 알고리즘: 덱으로 최대값 후보 인덱스 유지, 길이 N 배열의 sliding maximum을 O(N)에 계산

**결론 (2줄):**
- 기술사 판단: 문제의 순서 요구가 LIFO/FIFO/양단 중 무엇인지 먼저 식별하고, 배열·연결 리스트 구현을 용량 변동 기준으로 선택함
- 향후 방향: 멀티스레드 환경에서는 lock-free queue, bounded queue, backpressure 설계까지 함께 검토해야 함
