## 미리 알고가기

- $LIFO$: 마지막에 넣은 데이터를 가장 먼저 꺼내는 처리 규칙임
- $FIFO$: 먼저 들어온 데이터를 가장 먼저 꺼내는 처리 규칙임
- 덱($Deque$): 앞과 뒤 양쪽 끝에서 모두 넣고 뺄 수 있는 선형 자료구조임

## Ⅰ. 개요

- **정의/개념**: 스택, 큐, 덱은 데이터를 아무 위치에서나 꺼내지 않고 정해진 끝점에서만 넣고 빼도록 제한해 처리 순서를 보장하는 선형 자료구조임
- **배경/필요성**: 함수 호출, 작업 대기, 버퍼 처리처럼 들어온 순서와 꺼내는 순서가 결과를 바꾸는 구간에서는 임의 접근보다 연산 위치 규칙이 더 중요함

## Ⅱ. 특징

- 스택은 가장 최근 상태를 먼저 꺼내므로 되돌리기, 재귀 처리, 괄호 검사처럼 직전 작업을 다시 확인하는 흐름에 맞음
- 큐는 먼저 들어온 요청을 먼저 내보내므로 대기열, 메시지 전달, 스케줄링처럼 도착 순서를 보존해야 하는 업무에 적합함
- 덱은 앞뒤 양쪽에서 연산할 수 있어 한쪽은 입력, 다른 쪽은 제거처럼 역할을 나누거나 최근 값과 오래된 값을 함께 다뤄야 하는 구간에 유연함
- 세 구조는 저장 방식보다 어떤 순서를 보장해야 하는지가 선택 기준이 되므로 같은 데이터라도 목적에 따라 다른 구조를 써야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 데이터를 꺼내는 순서 | 가장 나중에 넣은 데이터가 먼저 나감 | 가장 먼저 들어온 데이터가 먼저 나감 | 앞이나 뒤 중 필요한 쪽에서 꺼낼 수 있음 |
| 주 연산 위치 | 한쪽 끝에서만 넣고 뺌 | 뒤에서 넣고 앞에서 뺌 | 앞과 뒤 양쪽 끝에서 모두 연산함 |
| 대표 용도 | 실행 취소, 함수 호출, 구문 분석에 주로 씀 | 작업 대기열, 버퍼, 메시지 전달에 주로 씀 | 슬라이딩 윈도우, 양방향 작업열, 최근값 관리에 주로 씀 |
| 설계 시 중점 | 직전 상태를 빠르게 되돌릴 수 있는지가 중요함 | 도착 순서를 흔들지 않고 처리하는지가 중요함 | 앞뒤 어느 쪽 연산이 더 자주 일어나는지 함께 봐야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 저장 공간 | 배열이나 연결 구조로 구현하며, 원소 수 상한이 분명하면 배열이 단순하고 크기 변화가 크면 연결 구조가 유연함 |
| 입출력 포인터 | $top$, $front$, $rear$는 현재 삽입과 삭제가 일어날 위치를 가리키며, 이 값이 틀리면 처리 순서 전체가 무너짐 |
| 공백과 포화 조건 | 비어 있는 상태와 가득 찬 상태를 구분하는 규칙이며, 경계 조건을 잘못 잡으면 꺼낼 값이 없는데 제거를 시도하거나 저장 공간을 넘어 덮어쓰는 오류가 발생함 |
| 순환 처리 | 큐와 덱은 원형 배열로 공간을 다시 쓰면 앞쪽 빈 칸을 재활용할 수 있어 불필요한 데이터 이동을 줄일 수 있음 |

```text
+---------+     +------------------+     +----------------+
| 저장 공간  | --> | top/front/rear   | --> | 삽입/삭제 규칙   |
+---------+     +------------------+     +----------------+
      |
      v
+----------------+
| 공백/포화 조건   |
+----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 요청도착 | --> | 위치선정 | --> | 삽입/삭제 | --> | 상태갱신 |
+----------+     +----------+     +----------+     +----------+
```

1. **요청도착**: 새 데이터를 넣거나 기존 데이터를 꺼내 달라는 연산 요청이 들어옴
2. **위치선정**: 스택, 큐, 덱의 규칙에 따라 어느 끝점에서 연산할지 결정함
3. **삽입/삭제**: 선택한 위치에 데이터를 저장하거나 꺼내어 다음 처리 단계로 넘김
4. **상태갱신**: 포인터와 원소 수를 갱신하고 빈 상태와 포화 상태를 다시 판정함

## Ⅵ. 실무 적용 및 유의점

1. 함수 호출과 괄호 검사는 최근 상태를 먼저 꺼내야 하므로 스택을 쓰고 최대 스택 깊이와 오류 검출률로 확인함
2. 메시지 대기열은 들어온 순서를 지켜야 하므로 큐를 쓰되 경계 상태 처리가 틀어지지 않게 하고 대기 길이와 처리량으로 확인함

## Ⅶ. 결론

스택, 큐, 덱은 구현 방식보다 어떤 순서로 데이터를 꺼내야 하는지가 더 중요하므로, 업무가 요구하는 처리 순서를 먼저 정한 뒤 구조를 골라야 함.
