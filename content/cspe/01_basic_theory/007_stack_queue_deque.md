# 스택·큐·덱 (Stack, Queue, Deque)

## 1. 개요

- **정의/개념**: 스택·큐·덱은 삽입과 삭제가 허용되는 위치를 기준으로 데이터 처리 순서를 통제하는 선형 추상 자료형이다.
- **배경/필요성**: 같은 데이터라도 어떤 원소를 먼저 꺼내는지에 따라 탐색 결과, 스케줄링 공정성, 버퍼 동작이 달라지므로 명확한 순서 규칙이 필요하다.

## 2. 특징 및 비교

| 구분 | 정의 | 연산 원리 | 대표 활용 |
|---|---|---|---|
| **스택(Stack)** | 한쪽 끝 Top에서 삽입·삭제 | LIFO | 함수 호출, DFS, Undo |
| **큐(Queue)** | Rear 삽입, Front 삭제 | FIFO | BFS, 작업 대기열, 메시지 버퍼 |
| **덱(Deque)** | Front·Rear 양쪽 삽입·삭제 | 스택+큐 일반화 | 슬라이딩 윈도우, work stealing |

- 배열 기반 구현은 캐시 친화적이지만 크기 한계와 오버플로우 관리가 필요하다.
- 연결 리스트 기반 구현은 크기 변화에 유연하지만 포인터 오버헤드가 있다.
- 원형 큐는 선형 큐의 공간 낭비를 해결하지만 Full/Empty 판정 규칙이 필요하다.
- 핵심 연산은 보통 `O(1)`이지만 탐색은 `O(n)`이며, 공간은 원소 수 기준 `O(n)`으로 본다.
- 선택 차원은 처리 순서, 연산 비용, 메모리·캐시 특성, 동시성, 경계 조건으로 압축한다.

따라서 구성요소는 원소 저장 자체보다 Top, Front, Rear가 처리 순서를 어떻게 통제하는지 중심으로 설명해야 한다.

## 3. 구성요소/구조

```text
Stack: Top -> push/pop
Queue: Front -> dequeue ... enqueue <- Rear
Deque: Front <-> add/delete <-> Rear
```

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Top | 스택의 삽입·삭제 위치 | LIFO 기준 |
| Front | 큐·덱의 삭제 기준 위치 | FIFO 시작점 |
| Rear | 큐·덱의 삽입 기준 위치 | FIFO 끝점 |
| Circular Index | 원형 큐의 포인터 갱신 방식 | `(index + 1) % n` |
| Empty/Full 조건 | 경계 상태 판정 | underflow/overflow 방지 |

이 구조가 곧 순서 보장과 경계 조건의 근거이므로, 오선택·Full/Empty 모호성·동시성 문제가 뒤따르는 핵심 리스크이다.

## 4. 문제점 및 개선방안

1. **순서 모델 오선택**
   - LIFO가 필요한 문제에 큐를 쓰면 DFS·복구 순서가 달라지고, FIFO가 필요한 문제에 스택을 쓰면 공정성이 깨진다.
   - **개선방안**: 입력·출력 예제로 처리 순서를 먼저 검증한다.

2. **원형 큐 Full/Empty 모호성**
   - `front == rear`만으로는 Empty와 Full을 구분하기 어렵다.
   - **개선방안**: count 변수를 두거나 한 칸을 비워두는 방식을 사용한다.

3. **동시성 문제**
   - 멀티스레드 생산자·소비자 환경에서 Race Condition이 발생할 수 있다.
   - **개선방안**: Lock-based 큐, Lock-free CAS 큐, 메모리 배리어 정책을 적용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 런타임 시스템 | 함수 호출 스택과 재귀 처리에 스택 사용 | 최대 스택 깊이, overflow |
| 메시지 처리 | 비동기 작업 버퍼와 메시지 큐에 큐 사용 | 큐 길이, 처리 지연 |
| 병렬 스케줄링 | work stealing에 덱 사용 | 작업 분산률, 경합률 |

## 6. 결론

스택·큐·덱은 처리 순서를 제어하는 기본 자료구조이다. LIFO·FIFO·양단 접근 원리뿐 아니라 시간·공간복잡도, 원형 큐 경계 조건, 동시성, 캐시 지역성까지 요구사항에 맞는 핵심 차원으로 비교해야 안정적으로 활용할 수 있다.
