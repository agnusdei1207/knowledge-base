## 미리 알고가기

- LIFO(Last-In, First-Out): 마지막 삽입 데이터가 먼저 제거되는 후입선출 규칙임
- FIFO(First-In, First-Out): 먼저 삽입된 데이터가 먼저 제거되는 선입선출 규칙임
- Deque(Double-Ended Queue): $Front$와 $Rear$ 양쪽에서 삽입·삭제를 허용하는 구조임
- 오버플로(Overflow): 가득 찬 저장체에 삽입을 요청한 상태임
- 언더플로(Underflow): 비어 있는 저장체에 삭제를 요청한 상태임

## 작성 근거(검토용)

- **개요 구성**: 허용 끝점과 제거 순서를 함께 정의해 세 자료구조의 공통 판단축을 세움
- **특징 선정**: 끝점 제한, 처리 순서, 포인터 갱신, 구현별 경계 관리는 선택과 검증의 핵심임
- **Ⅲ 비교축**: LIFO·FIFO·양방향 입출력이 활용 차이를 만들기 때문에 순서와 끝점 중심으로 정리함
- **구조 도식**: Top, Front, Rear 위치가 동작을 결정하므로 텍스트 모델로 배치함
- 깊은 DFS와 배열 큐는 호출 깊이·원소 이동 비용이 커지는 대표 구현 조건이라 남김

## Ⅰ. 개요

- **정의/개념**: 스택·큐·덱은 삽입·삭제가 허용되는 끝점과 제거 순서를 제한해 데이터 처리 순서를 통제하는 선형 자료구조임
- **배경/필요성**: 호출 이력·작업 대기열·버퍼링의 처리 순서를 통제하기 위해 입출력 규칙이 필요함

## Ⅱ. 특징

- 접근 끝점을 제한해 탐색·스케줄링·버퍼링의 처리 순서를 고정함
- 스택은 되돌림, 큐는 도착순 처리, 덱은 양끝 우선순위 조정에 맞음
- 끝점 포인터만 갱신하므로 정상 조건의 삽입·삭제 비용은 $O(1)$임
- 배열 구현은 오버플로, 연결 리스트 구현은 포인터 정합성을 주로 관리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스택 (Stack) | 큐 (Queue) | 덱 (Deque) |
|:---|:---|:---|:---|
| **처리 순서** | $LIFO$ | $FIFO$ | 양방향 입출력 |
| **주요 활용** | 재귀 호출·괄호 검사·DFS | 스케줄링·버퍼·BFS | 슬라이딩 윈도우·0-1 BFS·양방향 탐색 |
| **경계 조건** | $Top$ 경계 관리 | 원형 인덱스 또는 링크 관리 | 양끝 포인터 정합성 |
| **입출력 제약** | 한쪽 끝에서만 삽입·삭제 | 뒤에서 삽입하고 앞에서 삭제 | 양쪽 끝에서 삽입·삭제 |

> 요약: 작업의 역순 처리가 필요하면 스택을, 유입 순서대로 처리가 필요하면 큐를, 양방향 제어가 필요하면 덱을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 저장체 | 데이터를 담는 배열 또는 연결 리스트이며 용량 제한과 포인터 관리 방식을 결정함 |
| 제어 포인터 | $Top$, $Front$, $Rear$처럼 허용된 입출력 위치를 나타냄 |
| 상태 판정 | $Empty$와 $Full$을 검사해 언더플로·오버플로를 방지함 |
| 입출력 연산 | $Push/Pop$·$Enqueue/Dequeue$·양끝 삽입·삭제로 처리 순서를 구현함 |
| 경계 규칙 | 원형 큐의 한 칸 비움·크기 카운터·더미 노드로 모호한 포화 상태를 구분함 |

```text
[ 선형 자료구조 입출력 모델 ]
Stack:        Top -> [D3] -> [D2] -> [D1]
Queue:  Front [D1] -> [D2] -> [D3] Rear
Deque:  Front <-> [D1] <-> [D2] <-> Rear
```

> 요약: 스택·큐·덱은 허용 끝점이 처리 순서와 경계 오류 지점을 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 연산 요청    | --> | 상태 검사    | --> | 데이터 처리  | --> | 포인터 갱신  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **연산 요청**: 삽입($Push/Enqueue$) 또는 삭제($Pop/Dequeue$)를 받음
2. **상태 검사**: 삽입 전 $Full$, 삭제 전 $Empty$ 여부를 확인함
3. **데이터 처리**: 허용된 끝점 위치에 데이터를 쓰거나 읽어 반환함
4. **포인터 갱신**: $Top$, $Front$, $Rear$를 이동하고 경계 규칙을 확인함

> 요약: 삽입·삭제 전에 공백·포화 상태를 확인하고 허용된 끝점에서 데이터를 처리한 뒤 포인터를 갱신함.

## Ⅵ. 실무 사례

1. DFS·재귀 처리는 깊은 입력에서 호출 스택 한계를 넘으므로 명시적 스택으로 전환하고 최대 탐색 깊이와 메모리 사용량이 허용 한도 이내인지 확인함
2. 배열 큐는 앞쪽 삭제 때 이동 비용이 생기므로 원형 큐를 적용하고 공백·포화 경계 테스트로 확인함

## Ⅶ. 결론

- 스택·큐·덱은 처리 순서와 접근 끝점으로 선택하며, $O(1)$ 유지 조건과 경계 오류 검증이 구현 품질을 가름
