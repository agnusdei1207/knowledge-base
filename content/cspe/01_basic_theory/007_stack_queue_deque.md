## 미리 알고가기

- ADT: 내부 구현보다 외부에서 보이는 연산과 동작 규칙을 먼저 정의하는 추상 자료형(Abstract Data Type, ADT)임
- LIFO: 마지막에 삽입한 원소를 먼저 삭제하는 후입선출(Last-In First-Out, LIFO) 규칙임
- FIFO: 먼저 삽입한 원소를 먼저 삭제하는 선입선출(First-In First-Out, FIFO) 규칙임
- DFS/BFS: 깊이 우선 탐색(Depth-First Search, DFS)과 너비 우선 탐색(Breadth-First Search, BFS)은 각각 스택과 큐로 탐색 순서가 결정됨
- Front/Rear: 큐와 덱에서 삭제 또는 삽입 기준이 되는 양 끝 위치임
- Overflow/Underflow: 저장 공간 초과 또는 빈 구조 삭제처럼 경계 조건을 위반한 상태임

## Ⅰ. 개요

- **정의**: 스택·큐·덱은 삽입·삭제가 허용되는 위치를 기준으로 후입선출(Last-In First-Out, LIFO), 선입선출(First-In First-Out, FIFO), 양단 접근 순서를 통제해 선형 데이터의 처리 순서를 보장하는 추상 자료형임
- **배경/필요성**: 같은 원소 집합이라도 어떤 원소를 먼저 꺼내는지에 따라 알고리즘 결과와 시스템 공정성이 달라짐. 따라서 저장 공간보다 순서 규칙과 경계 조건을 먼저 정하고, 배열·연결 리스트·순환 버퍼 같은 구현을 선택해야 함
- **비유**: 스택은 접시 더미, 큐는 번호표 줄, 덱은 앞문과 뒷문을 모두 쓰는 셔틀과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 선형 추상 자료형(Abstract Data Type, ADT)의 순서 제어 방식과 선택 기준 확인 | LIFO, FIFO, 양단 연산, top/front/rear, overflow/underflow | 스택·큐 혼동, ADT와 구현 혼동, 경계 조건 누락 |

> 요약: 스택·큐·덱은 데이터를 어디에서 넣고 빼는지로 알고리즘의 처리 순서를 결정하는 선형 ADT임.

## Ⅱ. 특징/비교

| 판단 기준 | 스택 | 큐 | 덱 |
|:---|:---|:---|:---|
| 순서 규칙 | LIFO | FIFO | 양쪽 삽입·삭제 |
| 기준 위치 | top | front, rear | front, rear 모두 |
| 핵심 연산 | push, pop, peek | enqueue, dequeue, front | push/pop front, push/pop back |
| 대표 적용 | 함수 호출, 괄호 검사, DFS | BFS, 작업 대기열, 메시지 버퍼 | 슬라이딩 윈도우, 양방향 탐색 |
| 선택 기준 | 최근 상태를 먼저 되돌릴 때 | 도착 순서를 보존할 때 | 앞뒤 양쪽 접근이 모두 필요할 때 |

> 요약: 세 자료구조의 선택 기준은 평균 성능이 아니라 문제 요구와 처리 순서 규칙의 일치 여부임.

- 배열 구현은 연속 메모리와 인덱스로 O(1) 접근이 가능하지만 고정 용량과 재할당 비용을 고려해야 함
- 연결 리스트 구현은 크기 변화에 유연하지만 포인터 저장과 동적 할당 비용이 추가됨
- 순환 큐와 덱은 배열 공간 재사용에 유리하지만 front/rear 래핑 조건을 명확히 관리해야 함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력연산 | ---> | ADT 규칙 | ---> | 출력연산 |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 저장공간 |      | 위치포인터|      | 예외처리 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 저장 공간 | 배열, 순환 배열, 연결 리스트처럼 원소를 실제로 보관하는 기반 구조임 | 창고 |
| 위치 포인터 | top, front, rear처럼 삽입·삭제 기준 위치를 나타냄 | 출입구 표지 |
| 삽입 연산 | ADT 규칙에 맞는 끝 위치에 새 원소를 추가함 | 줄에 세우기 |
| 삭제 연산 | ADT 규칙에 맞는 위치에서 원소를 제거하고 반환함 | 차례대로 내보내기 |
| 예외 처리 | underflow, overflow, full/empty, 동시 접근 경합을 검증함 | 출입 통제 |

> 요약: 스택·큐·덱은 저장 공간 위에 위치 포인터와 삽입·삭제 규칙을 결합해 순서를 보장함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 요구확인 | ---> | 구조선택 | ---> | 연산수행 | ---> | 상태검증 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 순서규칙 |      | 구현방식 |      | 포인터갱신|      | 결과반환 |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 최근 원소 우선, 도착 순서 보존, 양방향 접근 중 필요한 순서 제약을 확인함
2. **구조와 구현 선택** - 스택, 큐, 덱을 선택하고 데이터 규모와 용량 변화에 따라 배열, 순환 배열, 연결 리스트를 정함
3. **핵심 연산 수행** - push, pop, enqueue, dequeue 같은 연산을 수행하며 top/front/rear를 갱신함
4. **검증/통제** - empty/full 조건, 순환 인덱스, 동시 접근 경합을 확인하고 원소 또는 상태를 반환함

> 요약: 절차는 처리 순서 요구를 ADT 규칙으로 바꾸고 위치 포인터를 일관되게 갱신하는 흐름임.

## Ⅴ. 문제점 및 개선방안

- **P1 순서 모델 오선택**: LIFO가 필요한 문제에 큐를 쓰거나 FIFO가 필요한 문제에 스택을 쓰면 탐색 순서, 스케줄링 공정성, 복구 순서가 달라짐
- **P2 경계 조건 오류**: 빈 구조 삭제, 꽉 찬 배열 삽입, 순환 인덱스 래핑 실수로 예외, 데이터 손실, 무한 대기가 발생할 수 있음
- **P3 동시 접근 경합**: 생산자와 소비자가 동시에 접근하면 원자성, 순서 보장, 메모리 가시성이 깨질 수 있음

> 요약: 스택·큐·덱의 운영 문제는 순서 규칙 선택, 경계 상태 검증, 동시성 통제에서 발생함.

### 개선방안

- **P1 대응**: 문제 요구를 상태 전이와 입출력 예제로 먼저 표현하고 DFS, BFS, undo/redo, 작업 대기열 요구에 맞춰 ADT를 선택함 (확인: 대표 입력의 출력 순서)
- **P2 대응**: empty/full 판정, 순환 배열의 한 칸 비움 또는 size 카운터 정책, 예외 반환 규칙을 구현 계약으로 고정함 (확인: 경계값 테스트)
- **P3 대응**: 단일 생산자·소비자, 다중 생산자·소비자 조건에 맞는 잠금 큐, lock-free 큐, 메모리 배리어 정책을 선택함 (확인: 동시성 스트레스 테스트)

> 요약: 개선은 순서 요구를 명시하고 경계·동시성 규칙을 테스트 가능한 계약으로 만드는 방식이 필요함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 런타임·컴파일러 | 호출 스택, 괄호 검사, 깊이 우선 탐색에 스택을 사용해 최근 상태를 먼저 처리함 | 최대 깊이, overflow 발생 여부 |
| 메시지·작업 처리 | 작업 대기열과 이벤트 버퍼에 큐를 적용하고, work stealing에는 덱을 적용함 | 큐 길이, 처리 지연, 경합률 |

> 요약: 스택·큐·덱은 처리 순서 자체가 요구사항인 런타임, 탐색, 작업 스케줄링에서 핵심 자료구조로 쓰임.

## Ⅶ. 전망

- **발전 방향**: 이벤트 기반 시스템, 스트리밍 처리, 병렬 런타임에서 큐와 덱은 작업 스케줄링, 백프레셔, work stealing의 기본 구조로 계속 활용됨
- **기술사적 판단**: 자료구조 선택은 Big-O만으로 판단하지 않고 처리 순서, 경계 조건, 동시 접근 요구, 구현 비용을 함께 비교해야 함
- **기술사 제언**: 답안에서는 세 자료구조를 한 표로 비교한 뒤 DFS·BFS·슬라이딩 윈도우 같은 적용 예시와 연결해 선택 이유를 설명하는 것이 효과적임
