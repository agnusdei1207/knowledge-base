## Ⅰ. 개요
- 해를 찾는 도중 가망이 없으면 되돌아가서 다른 경로를 찾는 탐색 기법임.
- 모든 경우의 수를 탐색하되 가지치기(Pruning)를 통해 효율을 높임.
- [표] 출제 의도: 상태 공간 트리 탐색 및 제약 만족 문제(CSP) 해결 능력 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  Root -> Node --(Pruning X)--> Backtrack
            \--(Ok)--> Deep

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| State Space Tree | 탐색 가능한 모든 상태를 트리로 표현 | 모든 갈림길 지도 |
| Pruning | 유망하지 않은 노드의 하위 탐색 중단 | 막다른 길 가지 않기 |
| DFS | 기본적으로 깊이 우선 탐색 방식 사용 | 한 우물 파기 |

> 요약: 가보지 않아도 안 되는 길을 미리 차단하여 탐색량을 줄임.

## Ⅲ. 절차
- ASCII 흐름도
  Start -> Visit -> Check Promising -> DFS(Next) / Backtrack

1. 시작 상태를 루트로 하여 깊이 우선 탐색을 수행함.
2. 현재 노드가 유망한지(제약 조건 만족 여부) 검사함.
3. 유망하면 하위 노드로 계속 진행(재귀 호출)함.
4. 유망하지 않으면 부모 노드로 돌아가(Backtrack) 다음 분기를 탐색함.

> 요약: 시도해보고 안 되면 즉시 철회하여 탐색 공간을 최적화함.

## Ⅳ. 문제점
- 가지치기가 제대로 되지 않을 경우 지수 시간복잡도(Exponential) 발생함.
- 최악의 경우 브루트 포스(Brute-force)와 성능 차이가 없음.

## Ⅴ. 개선방안
- 단기: 강력한 제약 조건을 설정하여 Pruning 효율을 극대화함.
- 중기: 비트마스크 등을 활용해 상태 체크 속도를 가속화함.
- 장기: A* 알고리즘의 휴리스틱을 결합하여 탐색 순서를 최적화함.

## Ⅵ. 전망
- N-Queen, 스도쿠, 외판원 문제(TSP) 등 조합 최적화에 필수적임.
- 논리 프로그래밍 언어(Prolog) 및 제약 충족 엔진의 핵심 메커니즘임.
