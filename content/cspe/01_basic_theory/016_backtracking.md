## 미리 알고가기

- 상태 공간 트리: 선택 가능한 모든 경로를 노드와 간선으로 표현한 탐색 구조임
- 부분해: 아직 완성 전이지만 현재까지 선택한 값들의 집합임
- 유망성(Promising): 현재 부분해를 제약을 만족하는 해로 확장할 수 있는지 판단하는 기준임
- 가지치기(Pruning): 유망하지 않은 경로를 더 확장하지 않고 중단하는 처리임
- 제약 충족 문제(CSP): 여러 제약을 동시에 만족하는 변수 값을 찾는 문제 유형임
- 분기 한정(Branch and Bound): 목적 함수의 경계값으로 현재 최적해보다 나은 해를 만들 수 없는 분기를 제거하는 탐색 기법임
- 깊이 우선 탐색(DFS): 한 경로를 끝까지 확장한 뒤 이전 분기점으로 되돌아가는 탐색 방식임

## 작성 근거(검토용)

- **개요 구성**: 백트래킹은 DFS 확장과 제약 위반 시 되돌아감이 핵심이라 정의에 두 동작을 함께 넣음
- **Ⅱ. 특징 선정**: 유망성 검사, 상태 복구, 지수적 시간복잡도는 성능과 정답성을 좌우해 특징으로 남김
- **Ⅲ. 비교축 선정**: 후보 제거 기준, 적용 문제, 성능 결정 요소는 세 전략의 원리·용도·비용 차이를 각각 드러냄
- **Ⅳ. 구조 선정**: 선택 목록, 부분해, 제약 함수, 복구 상태는 백트래킹 구현의 필수 요소라 표로 정리함
- 검사 비용과 변수 순서는 가지치기 효과를 바꾸므로 검증 지표와 연결함

## Ⅰ. 개요

- **정의/개념**: 백트래킹은 부분해를 깊이 우선으로 확장하다가 제약 위반이 확인되면 이전 선택으로 돌아가 다른 경로를 탐색하는 기법임
- **배경/필요성**: 후보 수가 지수적으로 증가하면 모든 경로를 확인하기 어려우므로 탐색 범위 축소가 필요함

## Ⅱ. 특징

- DFS 순서로 탐색하되 말단 노드에 도달하기 전이라도 제약을 위반하면 되돌아감
- 유망성 검사가 탐색 공간 크기와 실행 시간을 좌우함
- 상태 복구가 정확해야 다음 형제 경로가 이전 선택의 영향을 받지 않음
- 최악의 경우 시간복잡도가 지수적으로 증가하므로 가지치기 효과를 입력별로 확인해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 완전 탐색 (Brute-force) | 백트래킹 (Backtracking) | 분기 한정 (Branch & Bound) |
|:---|:---|:---|:---|
| 후보 제거 기준 | 제거 없이 완성 후보까지 확인 | 부분해가 제약을 위반하면 제거 | 현재 최적값을 개선할 수 없는 분기 제거 |
| 적용 문제 | 전체 후보 비교 | 제약 충족 문제 | 최적화 문제 |
| 성능 결정 요소 | 전체 후보 수 | 제약 강도·검사 순서 | 경계값의 정확도 |

> 요약: 제약 위반으로 경로를 중단하면 백트래킹, 목적 함수의 경계값으로 중단하면 분기 한정임.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 선택 목록 | 현재 깊이에서 시도할 후보값 |
| 부분해 | 현재까지 선택한 후보값의 집합 |
| 제약 함수 | 부분해의 확장 가능성 판정 |
| 상태 복구 | 다음 후보를 탐색할 수 있도록 선택 이전 상태로 되돌리는 연산 |
| 정답 판정 | 완성된 후보해의 제약 충족 검사 |

> 요약: 백트래킹은 선택을 부분해에 반영하고 제약 검사로 확장할 경로와 가지치기할 경로를 구분함.

## Ⅴ. 원리 및 절차 흐름도

```text
후보 선택 → 부분해 반영 → 유망성 판정
                         ├─ 제약 위반 → 가지치기
                         └─ 제약 충족 → 정답 판정
                                        ├─ 완성 → 정답 기록
                                        └─ 미완성 → 다음 깊이 탐색
                                                       ↓
                                                상태 복구·다음 후보
```

1. **후보 선택**: 현재 깊이에서 아직 시도하지 않은 후보를 부분해에 추가함
2. **유망성 검사**: 제약을 위반한 경로는 탐색을 중단함
3. **재귀 확장**: 유망하면 다음 깊이로 내려가 부분해를 확장함
4. **상태 복구**: 반환 후 선택을 취소하고 다음 후보를 검사함

> 요약: 백트래킹은 제약 검사로 경로를 중단하고 상태 복구로 다음 후보의 독립성을 유지함.

## Ⅵ. 실무 사례

1. 패키지 의존성 해석기는 후보 버전이 적은 패키지부터 결정해 실패 경로를 일찍 제거함
2. API 조합 테스트 생성기는 파라미터 제약을 위반한 조합을 더 이상 확장하지 않음

## Ⅶ. 결론

- 백트래킹은 답이 될 수 없는 경로를 일찍 버려 탐색량을 줄이며, 가지치기 기준과 상태 복구가 성능과 정확성을 좌우함
- 후보가 적고 강한 제약으로 탐색 공간을 줄일 수 있을 때 사용하며, 시간 한도를 넘으면 휴리스틱·SAT 해석기로 전환해야 함
