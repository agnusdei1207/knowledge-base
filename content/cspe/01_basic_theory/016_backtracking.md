# 📖 【암기용】 개념 완전 이해

> 목적: 백트래킹을 처음 보는 사람도 완전 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 가능한 해를 깊게 시도하다가 조건 위반 시 되돌아가는 탐색
- **왜 필요한가**: 모든 후보를 끝까지 검사하면 경우의 수가 폭발한다
- 중간에 불가능한 경로를 잘라야 N-Queen·스도쿠·조합 최적화 문제를 풀 수 있다
- **핵심 직관**: 미로에서 막다른 길을 만나면 직전 갈림길로 돌아가 다른 길을 고르는 방식이다.

## 깊이 이해
- **배경·문제의식**: 완전탐색은 해 공간 전체를 확인하므로 후보 수가 `b^d`로 증가한다
- 백트래킹은 제약 조건을 적용해 해가 될 수 없는 부분트리를 조기 제거한다
- **작동 원리**: 후보 선택, 제약 검증, 재귀 확장, 실패 시 상태 복원 순서로 진행한다
- 핵심은 `promising()` 함수가 불필요한 분기를 어느 시점에 제거하느냐이다
- **비유**: 시험 답안을 쓰다가 목차가 문제 요구와 맞지 않으면 해당 목차를 지우고 직전 목차 선택으로 돌아가는 과정과 같다.
- **구체 예시**: 8-Queen은 64칸 완전배치 대신 행 단위 1개 배치와 열·대각선 검증으로 후보 분기를 제거한다.
- **흔한 오해·주의점**: 백트래킹은 항상 최단해를 보장하지 않는다
- 최적해가 필요하면 가지한정(Branch and Bound) 또는 동적 프로그래밍 조건을 따로 검토해야 한다

## 연결 개념
- DFS — 백트래킹의 기본 순회 방식
- 가지치기(Pruning) — 불가능 후보 제거 기준
- 제약만족문제(CSP) — 변수·도메인·제약 기반 모델링

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 추상 표현 대신 조건·수치·판단 기준을 명시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 백트래킹은 DFS 기반 후보 탐색 중 제약 위반 경로를 즉시 중단하는 해 공간 탐색 기법이다.
> 2. **가치**: 후보 수 `b^d` 문제에서 중간 검증으로 탐색 노드 수를 줄여 N-Queen·순열·조합·CSP에 적용함.
> 3. **판단 포인트**: 후보 생성 순서, `promising()` 정확도, 상태 복원 누락 여부가 정답성과 수행시간을 좌우함.

---

## Ⅰ. 개요 및 필요성

- 정의: 백트래킹은 제약을 만족하는 해만 깊게 탐색하는 재귀 기법이다
- 배경: 완전탐색은 모든 후보를 끝까지 확인하므로 입력 크기 증가 시 계산량이 지수적으로 증가한다
- 필요성: 백트래킹은 불가능 후보를 조기 제거해 제한 시간 내 후보 검사를 줄인다

---

## Ⅱ. 구조 및 구성요소

```text
상태공간 트리 -> 후보 생성 -> 제약 검증 -> 재귀 확장
              / 통과: 상태 반영 -> 다음 깊이
              / 실패: 가지치기 -> 다음 후보
              / 종료: 해 저장 -> 상태 복원
```

| 구성요소 | 역할 | 판단 기준 |
|:---|:---|:---|
| 상태공간 트리 | 선택 단계와 후보 전체 표현 | 깊이 `d`, 분기수 `b` |
| 후보 생성 | 다음 선택값 나열 | 중복 제거, 사전순·휴리스틱 |
| 제약 검증 | 유망 후보 여부 판단 | 열·대각선·용량 등 조건 |
| 상태 복원 | 실패 분기 이전 상태 회귀 | 배열·비트마스크 원복 |

> 요약: 백트래킹은 상태공간 트리에서 후보를 만들고 제약 검증 후 재귀 확장·복원으로 해를 찾는다.

---

## Ⅲ. 동작원리 및 흐름도

```text
초기상태 -> 후보선택 -> promising 검증
        / 통과 -> 상태반영 -> 재귀호출 -> 해/복원
        / 실패 -> 가지치기 -> 다음후보
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 초기 상태·제약 정의 | 변수 수, 도메인, 종료 조건 |
| 2 | 후보 1개 선택 | 미방문·중복 여부 |
| 3 | 유망성 검사 | 제약 위반 0건 |
| 4 | 재귀 확장 또는 복원 | 해 발견, 후보 소진 |

> 요약: 후보 선택 후 제약을 통과한 경우만 재귀 확장하고, 실패 후보는 부분트리 전체를 제거한다.

---

## Ⅳ. 특징

| 구분 | 완전탐색 | 백트래킹 | 수치·기준 |
|:---|:---|:---|:---|
| 탐색 범위 | 모든 리프 노드 | 유망 노드 중심 | 최악 `O(b^d)` 유지 |
| 중단 시점 | 리프 도달 후 판단 | 중간 단계에서 판단 | N-Queen 대각선 즉시 검증 |
| 구현 요소 | 반복·재귀 | 재귀+복원+제약 | 스택 깊이 `d` |
| 한계 | 후보 폭발 | 제약 약하면 탐색량 증가 | `promising()` 비용 고려 |

> 요약: 백트래킹은 최악 지수시간을 없애지는 못하지만, 제약이 강한 문제에서 확인 노드 수를 줄인다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 완전탐색 | 백트래킹 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 모든 리프까지 확장 | 제약 위반 부분트리 제거 | 중간 제약 검사가 가능할 때 |
| 비용/성능 | 최악 O(b^d) | 최악 O(b^d), 평균 노드 감소 | pruning ratio 측정 필요 |
| 운영/위험 | 구현 단순 | 상태 복원 누락·제약 오류 | backtrack 후 불변식 검증 |

> 요약: 백트래킹은 최악 지수시간을 유지하므로 가지치기 비율과 상태 복원 정확도가 적용 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 상태 오염 | 복원 누락 | push/pop 대칭 구조, snapshot test | invariant violation count |
| 탐색 폭증 | 약한 promising 조건 | MRV, forward checking, bound 적용 | visited node count |
| 최적해 누락 | 가지치기 조건 과도 | 작은 입력 exhaustive 비교 | missed solution count |

> 요약: 백트래킹 리스크는 상태 오염, 탐색 폭증, 해 누락이며 불변식과 완전탐색 대조로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 가지치기 | pruning ratio 기록 | 탐색 카운터 |
| 정확도 | 작은 입력 해 집합 100% 일치 | brute force 대조 |
| 자원 | max depth와 실행시간 제한 준수 | 프로파일러 |

> 요약: 성공 기준은 가지치기율, 해 집합 정확도, 깊이·시간 제한 준수이다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. N-Queen: 열·좌상향·우상향 대각선을 비트마스크 3개로 관리해 검증을 `O(1)`로 수행함
2. 스케줄링 CSP: 변수-도메인-제약을 분리하고 MRV 휴리스틱으로 후보 순서를 조정함
3. 조합 탐색: 정렬 후 중복 후보를 건너뛰고 목표 합 초과 시 남은 분기를 제거함

**결론 (2줄):**
- 기술사 판단: 제약 검증 비용이 후보 확장 비용보다 작으면 백트래킹을 적용하고, 최적값 증명이 필요하면 가지한정을 결합함
- 향후 방향: CSP Solver·SAT Solver와 결합해 수작업 재귀보다 제약 모델 중심으로 전환 필요
