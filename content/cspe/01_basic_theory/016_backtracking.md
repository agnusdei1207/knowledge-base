# 백트래킹 (Backtracking)

## 1. 개요

- **정의/개념**: 백트래킹은 상태 공간 트리를 깊이 우선으로 탐색하다가 현재 부분 해가 제약을 만족하지 않으면 해당 분기를 중단하고 이전 상태로 되돌아가는 탐색 기법이다.
- **배경/필요성**: 완전탐색은 후보 수가 단계마다 곱해져 지수적으로 증가하므로, 정답 가능성이 없는 분기를 조기에 제거해 탐색량을 줄여야 한다.

백트래킹은 정답을 보장하면서도 불필요한 후보 생성을 줄이는 제약 기반 탐색 방식이다.

## 2. 특징 및 비교

| 구분 | 완전탐색 | 백트래킹 | 탐욕 알고리즘 |
|---|---|---|---|
| 탐색 범위 | 모든 후보 | 유망한 후보만 | 매 단계 선택 확정 |
| 정확성 | 보장 | 가지치기 조건이 안전하면 보장 | 증명 필요 |
| 비용 | 지수적 가능 | 최악 지수, 평균 감소 가능 | 대체로 낮음 |
| 핵심 조건 | 후보 생성 | 유망성 검사, 상태 복구 | 선택 기준 |

백트래킹은 DFS 기반이지만, 단순 DFS와 달리 제약 위반 분기를 즉시 버린다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| 상태 공간 트리 | 선택 가능한 후보를 트리로 표현 | 후보 구조 |
| 부분 해 | 현재까지 선택한 값 | 제약 검사 대상 |
| 유망성 검사 | 정답 가능성이 있는지 판단 | 가지치기 기준 |
| 상태 복구 | 선택을 취소하고 이전 상태로 복귀 | 오염 방지 |
| 종료 조건 | 완성 해 또는 불가능 상태 판정 | 정확성 보장 |

```text
선택 -> 제약 검사 -> 유망하면 재귀 탐색 -> 실패 시 선택 해제 -> 다음 후보
```

## 4. 문제점 및 개선방안

1. **지수적 탐색 폭발**
   - 가지치기가 약하면 완전탐색과 같은 수준의 시간이 걸린다.
   - **개선방안**: 후보 순서 휴리스틱, constraint propagation, bitmask로 분기 수를 줄인다.

2. **잘못된 가지치기**
   - 유망성 조건이 과도하면 실제 정답 후보를 제거할 수 있다.
   - **개선방안**: 작은 입력 완전탐색 결과와 비교해 정답 누락을 검증한다.

3. **상태 복구 오류**
   - 선택 해제나 전역 상태 복원이 누락되면 다른 분기 결과가 오염된다.
   - **개선방안**: 선택·재귀·해제를 한 블록으로 표준화하고 상태 불변식을 검사한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| N-Queen·스도쿠 | 제약 위반 후보를 조기에 제거 | 방문 노드 수, 정답 수 |
| 조합 최적화 | 용량·순서·충돌 조건을 만족하는 후보 탐색 | 가지치기율, 수행시간 |
| 테스트 케이스 생성 | 제약 조건을 만족하는 입력 조합 생성 | 커버리지, 생성 수 |

## 6. 결론

백트래킹은 완전탐색의 정확성을 유지하면서 제약 조건으로 탐색량을 줄이는 기법이다. 성능은 가지치기 품질과 상태 복구 정확성에 의해 결정되며, 최악 지수 시간 가능성을 항상 고려해야 한다.
