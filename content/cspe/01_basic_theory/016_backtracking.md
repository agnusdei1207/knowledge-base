## Ⅰ. 개요

- **정의**: 백트래킹(Backtracking)은 해 후보를 한 단계씩 확장하는 DFS 탐색 중 부분해가 제약 조건을 위반하는 시점에 그 지점에서 즉시 되돌아가, 하위 서브트리 전체를 가지치기(Pruning)하는 알고리즘임.
- **배경/필요성**: 조합 문제를 리프까지 전부 내려가 검증하는 전수 탐색은 후보 수가 지수적으로 늘어나므로, 부분해만으로 제약 위반을 조기에 판정해 해가 될 수 없는 서브트리를 통째로 배제하는 장치가 필요함.
- **출제 의도**: 유망 함수(Promising Function)의 정의와 구현력, 가지치기 없는 DFS·전수 탐색과의 차이 구분, N-Queens·스도쿠 등 대표 문제의 상태 공간 구조 이해를 확인함.
- **답안 방향**: 구조(부분해·유망 함수·백트랙 지점) → 동작(선택-검사-진행 또는 후퇴) → 비교(전수 탐색·분기 한정법) → 적용·결론 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 가지치기 구현력과 적용 조건 확인 | 유망 함수 정의, DFS 대비 조기 종료 지점, 최악 시간복잡도와 실제 탐색량의 차이 | 가지치기 없는 DFS를 백트래킹으로 서술, 전수 탐색과 구분 없이 설명 |

> 요약: 백트래킹 답안은 "어느 시점에 무엇을 근거로 되돌아가는가"라는 가지치기 조건을 먼저 못 박고, 그 위에서 전수 탐색 대비 절감을 논증해야 함.

## Ⅱ. 구조 및 구성요소

```text
탐색 시작(빈 부분해) -> 후보 선택 -> 유망 함수 검사
  -> 유망함: 부분해에 추가하고 다음 단계로 진행
  -> 유망하지 않음: 해당 서브트리 가지치기 -> 백트랙(직전 선택 취소)
-> 모든 후보 소진 시 상위 단계로 백트랙, 완성되면 해로 기록
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 부분해(Partial Solution) | 루트에서 현재 단계까지 선택된 값들의 목록 | 지금까지 걸어온 길 |
| 유망 함수(Promising Function) | 부분해가 제약 조건을 위반했는지 판정 | 막다른 길 감지기 |
| 가지치기(Pruning) | 유망하지 않은 서브트리 전체를 탐색에서 제외 | 통행 금지 표지 |
| 백트랙 지점(Backtrack Point) | 가지치기 후 되돌아갈 직전 선택 단계 | 마지막 갈림길 |

> 요약: 부분해를 한 단계씩 늘리다 유망 함수가 위반을 판정하면 그 지점에서 가지치기하고 백트랙 지점으로 돌아가는 구조임.

## Ⅲ. 동작원리 및 흐름도

```text
4-Queens(4x4 보드, 행마다 열 하나씩 배치, 열 번호 1~4)

행1: Q1=1 배치
행2: 열1(같은 열) 가지치기 -> 열2(대각선) 가지치기 -> 열3 통과 -> Q2=3 배치
행3: 열1~4 전부 같은 열 또는 대각선 위반으로 가지치기
  -> 행3에서 더 시도할 후보 없음 -> 백트랙(행2로 복귀)
행2: 열4 통과 -> Q2=4 배치
행3: 열2 통과 -> Q3=2 배치 -> 행4 전 열 위반으로 가지치기 -> 백트랙(행3으로 복귀)
행3: 남은 열도 모두 가지치기 -> 백트랙(행1로 복귀)
행1: Q1=2 배치 -> (동일 절차 반복) -> 해 (2,4,1,3) 발견
```

- 1단계(선택): 현재 단계에서 시도할 후보(N-Queens는 열 번호)를 하나 고름.
- 2단계(유망성 검사): 부분해가 제약 조건(같은 열·같은 대각선 등)을 위반하는지 확인함.
- 3단계(가지치기 또는 진행): 위반이면 해당 서브트리를 통째로 건너뛰고, 통과면 부분해에 추가해 다음 단계로 재귀함.
- 4단계(백트랙): 현재 단계의 모든 후보가 실패하면 부분해에서 마지막 선택을 제거하고 이전 단계로 복귀함.

> 요약: 위 예시처럼 행3에서 전 열이 실패하면 즉시 행2로, 다시 행1로 백트랙하며, 이 "실패 즉시 복귀"가 전수 탐색과의 유일한 차이임.

## Ⅳ. 특징

- 시간복잡도: 최악은 전수 탐색과 동일한 $O(N^N)$이나, 가지치기가 유효한 문제에서는 실제 방문 노드 수가 이보다 훨씬 작음.
- 공간복잡도: 부분해와 재귀 스택만 유지하므로 $O(N)$이며, 모든 후보를 동시에 저장하는 전수 탐색보다 메모리 사용이 적음.
- 상태 복원 의존성: 백트랙 시 부분해에서 마지막 선택을 반드시 제거해야 하며, 복원을 누락하면 이후 탐색이 오염됨.
- 성능 민감도: 유망 함수가 제약 조건 일부만 검사하면 가지치기 비율이 낮아져 전수 탐색에 근접하므로, 유망 함수의 정확성이 곧 성능임.

> 요약: 백트래킹의 실질 성능은 이론적 최악 복잡도가 아니라 유망 함수가 서브트리를 얼마나 일찍, 얼마나 정확히 잘라내는가에 좌우됨.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 기준 | 백트래킹 | 전수 탐색 | 분기 한정법 |
|:---|:---|:---|:---|
| 가지치기 기준 | 제약 위반 여부(타당성) | 없음(모든 리프 방문) | 비용 하한 > 현재 최적해 |
| 적용 문제 유형 | 해 존재 여부·열거(결정 문제) | 검증·소규모 문제 | 최적화 문제(최소/최대 비용) |
| 대표 사례 | N-Queens, 스도쿠, 그래프 색칠 | 소규모 순열 전수 검사 | 배낭 문제, 외판원 문제 |

> 요약: 세 방식 모두 상태 공간 트리를 탐색하되, 가지를 잘라내는 근거(위반 여부 vs 없음 vs 비용 하한)가 서로 다름 — 결정 문제면 백트래킹, 값 비교가 있는 최적화 문제면 분기 한정법을 선택함.

**리스크·대응 (불릿):**
- 유망 함수 미비: 제약 조건 일부만 검사해 가지치기 효과가 낮아짐 → 모든 제약을 유망 함수에 반영하고 방문 노드 수로 효과를 검증함.
- 최악 입력 방치: 가지치기가 거의 작동하지 않는 입력에서 실행 시간이 전수 탐색 수준으로 증가함 → 탐색 깊이 제한·타임아웃을 적용해 최악 실행 시간을 통제함.

**도입 후 점검 지표 (불릿):**
- 탐색 효율: 동일 입력에서 방문 노드 수를 전수 탐색 이론값과 비교해 가지치기 비율을 확인함.
- 정확성: 발견한 해가 모든 제약 조건을 만족하는지 검증 루틴으로 재확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 제약 조건 전체를 커버하는 유망 함수부터 정확히 구현해 가지치기 누락을 제거함.
2. 중기: 방문 노드 수·실행 시간을 계측해 유망 함수 강도별 성능 차이를 회귀 테스트로 관리함.
3. 장기: 최적화 목표가 추가되면 분기 한정법으로, 부분 문제가 중복되면 DP로 전환하는 기준을 설계 문서에 명시함.

- 기술사적 판단: 결정 문제(해 존재·열거)이고 제약 위반을 조기에 판정할 수 있을 때만 백트래킹을 선택하며, 최적값 비교가 필요하면 분기 한정법으로 확장함.
- 기술사 제언: 유망 함수의 제약 커버리지와 최악 실행 시간 상한을 도입 전 체크리스트로 고정함.
