# 016. 백트래킹 (Backtracking)

## 미리 알고가기

- **상태 공간 트리 (State Space Tree)**: 문제 해결 과정의 모든 선택지를 트리 구조로 나타낸 가상의 구조이며, 해를 찾는 과정은 이 트리를 탐색하는 것임
- **가지치기 (Pruning)**: 유망하지 않은 노드의 하위 트리 탐색을 중단하여 탐색 범위를 획기적으로 줄이는 기법임
- **DFS (깊이 우선 탐색)**: 백트래킹의 기본 탐색 메커니즘으로 사용되며, 한 경로를 끝까지 파고든 후 복귀하는 성질을 활용함

## Ⅰ. 개요

- **정의/개념**: 백트래킹(Backtracking)은 해를 찾는 과정에서 현재의 경로가 정답이 될 가능성이 없다고 판단되면(비유망), 즉시 탐색을 중단하고 이전 단계로 돌아가 다른 경로를 시도하는 알고리즘 설계 기법임
- **배경/필요성**: 모든 경우의 수를 조사하는 완전 탐색(Brute-force)은 지수 시간의 복잡도를 가져 현실적으로 처리가 불가능함. 제약 조건 위반 여부를 조기에 판단하여 불필요한 탐색량을 줄임으로써, 복잡한 조합 최적화 문제의 해를 효율적으로 구하기 위해 사용함

## Ⅱ. 특징 및 비교

백트래킹은 완전 탐색의 논리적 정확성을 유지하면서도, '유망성 검사'를 통해 실행 시간을 단축함.

| 비교 항목 | 완전 탐색 (Brute-force) | 백트래킹 (Backtracking) | 분기 한정 (Branch & Bound) |
|:---|:---|:---|:---|
| **탐색 방식** | 모든 노드 방문 | **유망한 노드만 방문** | 한계치(Bound)를 계산하여 방문 |
| **중단 시점** | 잎(Leaf) 노드 도달 시 | **제약 위반 즉시 (Pruning)** | 최적해보다 나쁠 것으로 예측 시 |
| **기본 구조** | 단순 반복/재귀 | **DFS 기반 재귀** | BFS 또는 Best-First Search |
| **효율성** | 매우 낮음 | 중간 (가지치기 효율에 의존) | 높음 (최적화 문제에 특화) |
| **보장 범위** | 모든 해 도달 | 모든 해 도달 가능 | 최적해 도달 가능 |

> 요약: 정답이 될 가능성이 '전혀 없는' 길을 일찍 포기함으로써 탐색 효율을 극대화함.

## Ⅲ. 구성요소/구조

백트래킹은 유망성 판단(Promising)과 상태 복구(State Recovery)가 핵심 로직을 이룸.

- **구성요소**:
  - **상태 정의**: 현재까지 선택한 결과물들의 집합
  - **유망성 검사 (Promising)**: 현재 노드에서 하위 노드로 내려갔을 때 해가 존재할 가능성이 있는지 판별
  - **선택과 해제**: 특정 후보를 선택하여 깊게 들어가고, 복귀 시에는 선택 전 상태로 되돌림
  - **종료 조건**: 해를 발견하거나 더 이상 탐색할 노드가 없는 상태

- **처리 로직 (원리/흐름도)**:

```text
[Backtracking Logic]
Function solve(state):
  1. if (is_solution(state)): 
       print/return solution
  2. for (next_candidate in candidates):
       if (is_promising(state, next_candidate)):
         apply(next_candidate)  -- 상태 변경
         solve(state)           -- 재귀 탐색
         undo(next_candidate)   -- 상태 복구(Backtrack)
```

1. **시도**: 가능한 후보 중 하나를 선택하여 상태를 갱신함
2. **검증**: 제약 조건을 만족하는지(Promising) 확인하고, 만족하면 더 깊은 단계로 진행함
3. **복귀**: 하위 탐색이 끝나면(성공/실패 무관) 방금 선택한 후보의 영향을 지우고 원상태로 복구함

## Ⅳ. 문제점 및 개선방안

1. **가지치기 효율에 따른 성능 편차**: 유망성 검사가 느슨하거나 제약 조건이 약할 경우, 결국 지수 시간($O(2^n)$ 또는 $O(n!)$)에 도달하여 시스템이 멈춤
   - **개선방안**: 제약 전파(Constraint Propagation)를 통해 후보군을 미리 필터링하거나, 탐색 순서를 최적화하는 휴리스틱(가장 제약이 심한 칸부터 채우기 등)을 적용함 (확인: 탐색 노드 수 감소량)

2. **메모리 오버헤드와 복구 오류**: 재귀 호출이 깊어지면 스택 메모리가 부족해질 수 있으며, 상태 복구 시 실수가 발생하면 전체 탐색 결과가 오염됨
   - **개선방안**: 전역 변수 대신 매개변수로 상태를 전달하거나, 비트마스킹(Bitmasking)을 사용하여 상태 저장과 복구를 정수 연산 수준으로 단순화함 (확인: 복귀 후 상태 일관성 검증)

3. **중복 상태의 반복 탐색**: 동일한 부분 문제나 상태를 여러 경로에서 반복적으로 탐색하여 시간 낭비 발생
   - **개선방안**: 이미 계산된 상태의 유망성 여부를 저장하는 **메모이제이션(Memoization)**을 결합하여 DP와 백트래킹의 장점을 섞은 형태로 구현함 (확인: 동일 상태 재방문 횟수)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| N-Queen / 스도쿠 | 퀸을 놓거나 숫자를 채울 때마다 행, 열, 대각선 충돌을 체크하여 유효하지 않으면 즉시 중단 | 정답 도출 시간, 탐색 노드 수 |
| 설정 최적화 (SAT) | 수많은 논리 조건들을 모두 만족하는 변수 조합을 찾기 위해 분기하며 제약 위반 시 복귀 | 불만족 조건 개수, 수렴 속도 |
| 경로 탐색 (Hamiltonian) | 모든 도시를 한 번씩만 방문하는 경로를 찾을 때, 이미 방문한 도시를 다시 선택하려 하면 가지치기 | 전체 경로 길이, 방문 도시 수 |
| 퍼즐 및 게임 AI | 체스, 오목 등에서 수읽기를 수행할 때 승리 가능성이 낮은 악수를 조기에 배제 (알파-베타 가지치기) | 탐색 깊이, 승률 및 수읽기 성능 |

> 요약: 가능한 모든 조합을 검토해야 하지만 정답이 아닌 가지만 잘 쳐내도 성능이 보장되는 모든 탐색 문제에 적용됨.

## Ⅵ. 결론

백트래킹은 '가능성의 지도'에서 절망적인 길을 빠르게 포기함으로써 희망적인 길에 집중하는 지능적인 탐색 기법임. 기술사는 백트래킹 구현 시 단순히 재귀를 돌리는 것에 그치지 않고, '어떻게 하면 더 일찍 가망 없는 가지를 찾아낼 것인가'라는 유망성 검사 최적화에 역량을 집중해야 함.

또한 시스템의 스택 제약과 메모리 지역성을 고려하여 명시적 스택이나 비트 연산을 도입하는 등 로우레벨 최적화 기술을 병행해야 함. 결국 백트래킹은 완전 탐색의 정확성과 효율적 배제라는 양면성을 다루는 기술이며, 이를 통해 난해한 조합 문제를 실용적인 시간 내에 해결하는 능력이 필수적임.
