## 미리 알고가기

- 상태 공간 트리: 가능한 선택을 단계별 노드와 간선으로 표현한 탐색 공간임
- 후보 해: 아직 완성되지 않았지만 해가 될 가능성이 있는 부분 선택임
- 유망성 검사: 현재 후보가 제약을 만족해 해로 확장될 수 있는지 판단하는 과정임
- 가지치기: 유망하지 않은 후보의 하위 탐색을 중단하는 최적화임
- 되돌리기: 선택을 취소하고 이전 상태로 복구해 다른 후보를 탐색하는 동작임

## Ⅰ. 개요

- **정의**: 백트래킹은 상태 공간 트리를 탐색하다가 현재 부분 해가 제약을 만족하지 않으면 해당 분기를 중단하는 탐색 기법임
- **배경/필요성**: 완전탐색은 후보 수가 단계마다 곱해져 지수적으로 늘어나므로, 정확성을 유지하면서 제약 위반 분기를 조기에 버려 탐색량을 줄이는 기법이 필요해짐. 다만 가지치기 조건이 약하면 여전히 지수 시간이 걸리며, 상태 복구가 틀리면 이후 탐색 결과까지 오염됨.
- **비유**: 미로에서 막다른 길임을 확인하면 그 길의 끝까지 더 가지 않고 마지막 갈림길로 돌아가 다른 길을 선택하는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 조합 탐색 최적화 이해 확인 | 상태 공간 트리, DFS, 유망성 검사, 가지치기, 상태 복구 | 단순 재귀와 혼동, 지수 비용 누락 |

> 요약: 백트래킹은 해 후보를 깊이 우선 탐색(Depth-First Search, DFS)으로 확장하되 제약 위반 분기를 조기에 버려 탐색량을 줄이는 기법임.

## Ⅱ. 특징/비교

| 판단 기준 | 완전탐색 | 백트래킹 | 분기한정 |
|:---|:---|:---|:---|
| 탐색 방식 | 모든 후보 확인 | 제약 위반 후보를 중단 | bound로 최적 가능성 낮은 후보 중단 |
| 적용 대상 | 입력이 작거나 검증용 | 제약 충족, 조합 탐색 | 최적화 문제 |
| 정확성 | 모든 해 확인으로 보장 | 가지치기가 안전할 때 보장 | bound가 타당할 때 보장 |
| 비용 특성 | 지수적으로 증가 | 최악은 지수, 실제는 pruning 의존 | bound 품질에 의존 |
| 선택 기준 | 후보 수가 작을 때 | 제약으로 조기 탈락 가능할 때 | 최적값 상하한이 있을 때 |

> 요약: 백트래킹은 완전탐색의 후보를 모두 만들기 전에 제약으로 잘라내는 DFS 기반 탐색임.

- 대표 문제는 N-Queen, 스도쿠, 부분집합 합, 순열 생성, 그래프 색칠 등이 있음
- 유망성 검사는 정답이 될 수 있는 후보를 잘못 제거하지 않아야 함
- 후보를 제약 위반 가능성이 큰 순서(예: 남은 선택지가 적은 변수 우선)로 배치하면 최악 시간은 지수 그대로여도 평균 방문 노드 수가 줄어듦

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 부분해   | ---> | 후보생성 | ---> |유망성검사|
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 상태공간 |      | 선택/해제|      | 해목록   |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 상태 공간 트리 | 선택 단계별 가능한 후보를 트리 형태로 표현한 전체 탐색 공간임 | 갈림길 지도 |
| 부분 해 | 현재까지 선택한 값들의 조합이며 아직 완성되지 않았을 수 있음 | 지나온 경로 |
| 후보 생성 | 다음 단계에서 선택 가능한 값들을 만드는 과정임 | 다음 갈림길 목록 |
| 유망성 검사 | 제약을 위반하거나 목표 달성이 불가능한 후보를 걸러냄 | 막다른 길 확인 |
| 상태 복구 | 선택 전 상태로 되돌려 다른 후보 탐색을 가능하게 함 | 갈림길로 돌아가기 |

> 요약: 백트래킹은 부분 해를 확장하면서 유망성 검사를 통과한 후보만 깊게 탐색하는 구조임.

- 상태는 전역 배열로 관리할 수도 있지만 선택과 해제 순서가 엄격히 맞아야 함
- 유망성 검사는 빠르게 실행되어야 하며, 검사 비용이 크면 가지치기 이점이 줄어듦
- 해가 하나 필요한지 모든 해가 필요한지에 따라 종료 조건이 달라짐

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 상태진입 | ---> | 후보선택 | ---> | 유망검사 | ---> | 재귀/복구|
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 종료판정 |      | 선택반영 |      | 가지치기 |      | 해저장   |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 해의 형태, 제약 조건, 하나의 해인지 전체 해인지, 탐색 깊이를 정의함
2. **후보 생성과 선택** - 현재 상태에서 가능한 후보를 만들고 하나를 선택해 부분 해에 반영함
3. **유망성 검사와 재귀** - 제약을 만족하면 다음 깊이로 재귀 탐색하고, 위반하면 해당 분기를 중단함
4. **상태 복구와 출력** - 재귀 복귀 후 선택을 취소하고 다른 후보를 탐색하며 완성된 해를 저장하거나 반환함

> 요약: 백트래킹 절차는 선택, 검사, 재귀, 복구를 반복해 유효한 해만 깊게 탐색하는 흐름임.

- 후보 순서를 잘 정하면 같은 정답 보장 아래에서 평균 탐색 깊이를 줄일 수 있음
- 제약 검사를 누적 자료구조로 관리하면 매번 전체 상태를 검사하지 않아도 됨
- 재귀 종료 조건은 깊이 도달, 목표 만족, 후보 소진을 구분해야 함

## Ⅴ. 문제점 및 개선방안

- **P1 지수적 탐색 폭발**: 가지치기가 약하면 후보 수가 단계별로 곱해져 최악의 경우 완전탐색과 같은 지수 시간이 걸림
- **P2 잘못된 가지치기**: 유망성 검사가 과도하면 실제 정답이 될 수 있는 후보를 제거해 정확성이 깨짐
- **P3 상태 복구 오류**: 선택 해제나 전역 상태 복원이 누락되면 다른 분기 탐색에 이전 상태가 섞임

> 요약: 백트래킹의 위험은 탐색량, 가지치기 안전성, 상태 복구 정확성에서 발생함.

### 개선방안

- **P1 대응**: 후보 순서 휴리스틱, constraint propagation, bitmask, 중복 제거로 분기 수를 줄임 (확인: 방문 노드 수)
- **P2 대응**: 가지치기 조건을 필요조건 중심으로 설계하고 작은 입력 완전탐색과 결과를 비교함 (확인: 정답 누락 테스트)
- **P3 대응**: 선택과 해제를 한 블록에 배치하고 상태 스냅샷 또는 RAII(Resource Acquisition Is Initialization) 패턴으로 복구를 자동화함 (확인: 분기별 상태 불변식)

> 요약: 백트래킹 개선은 안전한 가지치기와 상태 복구 규칙을 강화해 탐색량을 줄이는 방향임.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 제약 충족 문제 | N-Queen, 스도쿠, 배치 제약처럼 후보를 선택하고 유망성 검사로 가지치기함 | 방문 노드 수, 정답 누락 여부 |
| 설정 조합 검증 | 호환 가능한 옵션 조합만 탐색해 구성 오류를 사전에 찾음 | 탐색 시간, 제약 위반 검출률 |

> 요약: 백트래킹은 모든 조합을 열거하되 안전한 가지치기로 후보 공간을 줄이는 제약 문제에 적합함.

## Ⅶ. 전망

- **발전 방향**: 제약 충족 문제, 퍼즐, 조합 최적화에서는 백트래킹이 SAT(Boolean Satisfiability, 논리식 만족) 및 CP(Constraint Programming, 제약 프로그래밍) Solver, 휴리스틱 탐색, 병렬 탐색과 결합되어 활용됨
- **기술사적 판단**: 백트래킹은 느린 완전탐색이 아니라 제약을 이용해 후보를 줄이는 정확 탐색으로 설명해야 함
- **기술사 제언**: 답안에서는 상태 공간 트리와 유망성 검사를 도식화하고, 최악 시간은 여전히 지수적임을 명시해야 함
