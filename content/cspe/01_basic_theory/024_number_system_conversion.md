## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 수 체계 변환(Number System Conversion)은 같은 수량을 **다른 진법(Base/Radix)**으로 표현하는 것이다. 컴퓨터 내부는 이진법(Base-2), 사람은 십진법(Base-10), 프로그래밍에서는 16진법(Base-16)과 8진법(Base-8)을 주로 사용한다. 진법 간 변환은 나눗셈·곱셈 반복, 또는 비트 그룹핑으로 수행한다.
> 2. **가치**: 메모리 주소(16진), 파일 권한(8진), MAC 주소(16진), IPv6(16진), 디버깅(메모리 덤프) 등 시스템 프로그래밍과 네트워크에서 진법 변환은 일상 업무이다. 변환 원리를 이해하지 않으면 디버깅과 설계가 불가능하다.
> 3. **융합**: 하드웨어(비트·바이트 단위 연산), 네트워크(IP/MAC 주소), 보안(해시값 16진 표기), 운영체제(메모리 매핑), 웹(색상 코드 #RRGGBB) 등 CS 전 분야에서 진법 변환이 사용된다.

---

## Ⅰ. 개요 및 필요성

- **개념**: 진법(Base-N)은 N개의 숫자 기호로 수를 표현하는 체계이다. 이진법은 {0,1}, 8진법은 {0-7}, 10진법은 {0-9}, 16진법은 {0-9, A-F}를 사용한다. 같은 수 255는 이진법으로 11111111₂, 8진법으로 377₈, 16진법으로 FF₁₆이다.

- **필요성**: 컴퓨터는 전압의 고/저(1/0)로 데이터를 표현하므로 본질적으로 이진법이다. 그러나 이진수는 길어서 사람이 읽기 어렵다. 16진법은 4비트를 한 자리로 압축하여 가독성을 높이면서도 이진↔16진 변환이 즉각적이다(4비트 그룹핑).

- **비유**: 수 체계 변환은 **외국어 번역**과 같다. 같은 뜻(수량)을 한국어(10진), 영어(2진), 일본어(16진)로 표현하는 것이다. 2진→16진은 "영어 4단어를 일본어 한 글자로 축약"하는 것과 같다.

- **등장 배경 및 발전 과정**:
  1. **고대**: 바빌로니아(60진법), 마야(20진법) 등 다양한 진법이 존재했다.
  2. **17세기**: 라이프니츠가 이진법의 수학적 기초를 정립했다.
  3. **현대**: ASCII(7비트), Unicode(16비트/32비트), IPv6(128비트 16진 표기) 등 디지털 시대에 진법 변환은 필수 기술이 되었다.

```text
+-----------------------------------------------------------------------+
|        10진수 156을 2진·8진·16진으로 변환                             |
+-----------------------------------------------------------------------+
|                                                                       |
|  [10진 → 2진: 나눗셈 반복법]                                         |
|  156 ÷ 2 = 78 ... 0                                                 |
|   78 ÷ 2 = 39 ... 0                                                 |
|   39 ÷ 2 = 19 ... 1                                                 |
|   19 ÷ 2 =  9 ... 1     결과: 나머지를 아래→위로 읽음               |
|    9 ÷ 2 =  4 ... 1     156₁₀ = 10011100₂                           |
|    4 ÷ 2 =  2 ... 0                                                 |
|    2 ÷ 2 =  1 ... 0                                                 |
|    1 ÷ 2 =  0 ... 1 ↑                                               |
|                                                                       |
|  [2진 → 8진: 3비트 그룹핑]                                          |
|  10 011 100₂                                                         |
|   2   3   4 → 234₈                                                  |
|                                                                       |
|  [2진 → 16진: 4비트 그룹핑]                                         |
|  1001 1100₂                                                          |
|    9    C → 9C₁₆                                                    |
|                                                                       |
|  ★ 핵심: 2↔8은 3비트, 2↔16은 4비트 그룹핑으로 즉각 변환            |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 10진수 156을 이진수로 변환할 때 2로 반복 나눗셈하여 나머지를 역순으로 읽는다. 이진↔8진은 3비트씩, 이진↔16진은 4비트씩 그룹핑하면 즉각 변환된다. 이것이 프로그래밍에서 8진법과 16진법이 선호되는 이유이다 — 이진법과의 변환이 나눗셈 없이 그룹핑만으로 가능하기 때문이다.

- **📢 섹션 요약 비유**: 10진→2진 변환은 "피자를 반씩 나누면서 남는 조각을 기록하기"이고, 2진→16진은 "4조각씩 묶어서 한 봉지에 담기"입니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 변환 방법 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **나눗셈 반복법** | 정수부 10진→N진 | 몫이 0이 될 때까지 N으로 나눔, 나머지 역순 | 모든 진법 변환 | 피자 반씩 나누기 |
| **곱셈 반복법** | 소수부 10진→N진 | N을 곱해 정수부 추출 반복 | 소수점 이하 변환 | 물 따르기 |
| **3/4비트 그룹핑** | 2↔8/16 즉각 변환 | 비트를 3/4개씩 묶어 변환 | 메모리 덤프, 디버깅 | 카드 묶기 |
| **가중치 전개법** | N진→10진 | 각 자릿수 × N^(자릿수 위치) 합산 | 이해·검증용 | 자릿값 계산 |

### 소수부 변환 — 0.1₁₀의 이진 표현

```text
+-----------------------------------------------------------------------+
|        10진 소수 0.1의 2진 변환 — 무한 순환 소수가 된다!              |
+-----------------------------------------------------------------------+
|                                                                       |
|  [곱셈 반복법]                                                        |
|  0.1 × 2 = 0.2 → 정수부 0                                           |
|  0.2 × 2 = 0.4 → 정수부 0                                           |
|  0.4 × 2 = 0.8 → 정수부 0                                           |
|  0.8 × 2 = 1.6 → 정수부 1                                           |
|  0.6 × 2 = 1.2 → 정수부 1                                           |
|  0.2 × 2 = 0.4 → 정수부 0  ← 순환 시작!                            |
|  ...                                                                  |
|                                                                       |
|  0.1₁₀ = 0.000110011001100...₂ (무한 반복)                          |
|                                                                       |
|  ★ 이것이 0.1 + 0.2 ≠ 0.3 (부동소수점 오류)의 원인!                |
|  0.1₁₀ + 0.2₁₀ = 0.30000000000000004₁₀ (IEEE 754 double)           |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 10진 소수 0.1은 이진수로 정확히 표현할 수 없어 무한 순환 소수가 된다. 컴퓨터는 유한 비트로 잘라서 저장하므로 오차가 발생한다. 이것이 모든 프로그래밍 언어에서 `0.1 + 0.2 ≠ 0.3`이 되는 근본 원인이며, 금융 계산에서 float 대신 Decimal 타입을 사용해야 하는 이유이다.

- **📢 섹션 요약 비유**: 소수부 진법 변환은 "1/3을 소수로 쓰면 0.333...이 되는 것"과 같습니다. 10진법에서 정확한 수가 2진법에서는 무한 소수가 됩니다.

## Ⅲ. 비교 및 연결

### 비교 1: 진법별 특성

| 비교 항목 | 이진법 (Base-2) | 8진법 (Base-8) | 10진법 (Base-10) | 16진법 (Base-16) |
|:---|:---|:---|:---|:---|
| **자릿수** | 가장 길다 | 중간 | 익숙함 | 가장 짧다 |
| **컴퓨터 친화성** | 직접 대응 | 3비트 그룹핑 | 변환 필요 | 4비트 그룹핑 |
| **주요 용도** | 비트 연산 | Unix 파일 권한(755) | 사람의 계산 | 메모리 주소, 색상 코드 |
| **가독성** | 나쁨 | 보통 | 우수 | 좋음 |

### 과목 융합 관점
- **네트워크**: IPv4 주소(192.168.1.1)는 각 옥텟이 8비트 이진수의 10진 표기이고, IPv6(fe80::1)는 16비트씩 16진 표기이다. MAC 주소(AA:BB:CC:DD:EE:FF)도 16진법이다.
- **보안**: SHA-256 해시값은 256비트를 64자리 16진수로 표현한다(e.g., `a5b9...`). 이진으로 쓰면 256자리, 16진으로 쓰면 64자리.
- **웹**: CSS 색상 코드 `#FF5733`은 RGB 각 채널을 16진 2자리(8비트)로 표현한 것이다.

- **📢 섹션 요약 비유**: 진법은 "같은 돈을 원화, 달러, 엔화로 표기하는 것"과 같습니다. 한국에서는 원화(10진), 컴퓨터에서는 달러(2진), 프로그래머에게는 엔화(16진)가 편합니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — 메모리 덤프 디버깅**: 프로그램 크래시 시 코어 덤프를 16진 에디터로 열어 메모리 내용을 확인한다. 각 바이트가 2자리 16진수로 표시되며, 주소도 16진이다. 16진↔이진 변환이 즉각적이어야 비트 단위 분석이 가능하다.

2. **시나리오 — Unix 파일 권한 설정**: `chmod 755 file`에서 7=111₂(rwx), 5=101₂(r-x)이다. 각 8진수 한 자리가 3비트(읽기·쓰기·실행)에 직접 대응하므로, 8진법이 파일 권한 표현에 최적이다.

### 도입 체크리스트
- **기술적**: 표현 대상의 비트 수가 3의 배수(→8진)인가, 4의 배수(→16진)인가?
- **운영 및 보안적**: 16진 표기 시 대소문자 통일(RFC 5952: IPv6는 소문자 권장), 접두사(`0x`, `0o`, `0b`) 명시.

### 안티패턴
- **10진 직접 비트 연산**: 10진수로 비트마스크를 계산하면 오류가 잦다. 반드시 16진(`0xFF`)이나 2진(`0b11111111`)으로 표현한다.

- **📢 섹션 요약 비유**: 수 체계를 모르고 시스템 프로그래밍을 하는 것은 "한글도 모르면서 한국어 소설을 쓰려는 것"과 같습니다.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 진법 미숙 | 진법 능숙 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | 메모리 덤프 해석 30분 | 16진 즉독 5분 | **6배** 빠른 디버깅 |
| **정성** | 비트 연산 오류 빈발 | 16진 마스크로 정확한 연산 | 버그 감소 |

### 미래 전망
- **양자 컴퓨팅**: 큐비트 기반 수 체계(양자 상태의 표현)가 기존 이진법을 확장할 가능성.

### 참고 표준
- **IEEE 754**: 부동소수점 표준 (이진 표현 기반)
- **RFC 5952**: IPv6 주소 텍스트 표현 권장 형식

수 체계 변환은 CS의 "알파벳"이다. 2진·8진·16진을 자유롭게 오가는 능력이 시스템 레벨 프로그래밍과 디버깅의 전제 조건이다.

### 👶 어린이를 위한 3줄 비유 설명

1. 우리는 손가락이 10개라서 10진법(0~9)을 써요. 컴퓨터는 스위치가 2개(켜짐/꺼짐)라서 2진법(0,1)을 써요!
2. 2진법으로 숫자를 쓰면 너무 길어요(255 = 11111111). 그래서 4개씩 묶어 16진법으로 쓰면 FF, 딱 2글자!
3. 같은 숫자를 다른 언어로 말하는 것처럼, 255(한국어) = 11111111(컴퓨터어) = FF(프로그래머어)예요!
