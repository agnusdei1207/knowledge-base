## 미리 알고가기

- 기수($r$): 각 자리에 허용된 기호 개수이며 진법을 결정함
- 위치 가중치: 자리 위치에 따라 $r^i$가 곱해지는 자리값 기준임
- 비트 그룹화: 2진수를 3비트나 4비트씩 묶어 8진수·16진수로 바꾸는 방식임
- 정수부 변환: 목표 기수로 반복 나눗셈을 수행하고 나머지를 역순으로 읽음
- 소수부 변환: 목표 기수를 반복 곱하고 정수 부분을 순서대로 읽음
- 정밀도 손실: 유한 자리로 표현하지 못하는 소수가 잘리거나 반올림되는 현상임

## 작성 근거(검토용)

- **개요 구성**: 같은 값의 표현 변경이라는 핵심을 먼저 제시해 변환을 단순 암산 기법으로만 보지 않게 함
- **Ⅱ. 특징 선정**: 값 보존·직접 변환·10진수 경유·소수 정밀도라는 실무 오류 지점을 중심으로 선별함
- **Ⅲ. 비교축 선정**: 이진·8진·16진과 10진수를 같은 표에 배치해 변환 경로를 명확히 함
- **Ⅳ·Ⅴ. 구조·절차 선정**: 자리 기호·기수·위치 가중치의 관계로 값 보존 구조를 설명하고, 기수 식별부터 검증까지의 변환 절차를 배치함
- **Ⅵ·Ⅶ. 사례·결론 선정**: 주소·패킷 해석과 소수 오차처럼 실제 시스템에서 잘못 변환되는 경우를 남김
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 값 보존 정의와 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 수 체계 변환은 같은 값을 서로 다른 기수의 자리값 표현으로 바꾸어 컴퓨터 내부 표현과 사람이 읽는 표현을 연결하는 절차임
- **배경/필요성**: 주소·명령·권한·색상 값의 정확한 해석을 위해 진법 간 변환 기준이 필요함

### 쉽게 이해하기 (학습용)
- 같은 물건 개수를 12개들이 상자로 세든 10개들이 묶음으로 세든 실제 개수는 그대로이듯, 진법 변환도 값은 그대로 두고 세는 단위(자리 기호)만 바꾸는 절차임

## Ⅱ. 특징

- 변환 전후의 수치값은 같고, 달라지는 것은 기수와 자리 기호의 표현 방식임
- 8진수와 16진수의 한 자리는 각각 2진수 3비트와 4비트에 대응하므로 비트 묶음으로 직접 변환함
- 10진수가 포함되면 위치 가중치 합산이나 반복 나눗셈·곱셈을 사용함
- 소수부는 반복 패턴이 생길 수 있어 자릿수 제한과 반올림 기준이 필요함

### 쉽게 이해하기 (학습용)
- 8진수와 16진수는 2진수를 3자리·4자리씩 묶기만 하면 되는 간단한 포장 교체이고, 10진수가 끼면 자리마다 값을 곱해 더하거나 나눠보는 계산이 필요함
- 소수점 아래는 아무리 나눠도 딱 안 맞아떨어지는 경우가 있어 어디서 끊을지 미리 정해둬야 함

## Ⅲ. 종류 및 비교

| 진법 | 사용 기호 | 2진수와의 변환 기준 | 주요 활용 |
|:---|:---|:---|:---|
| 2진수 | 0·1 | 1자리와 1비트가 대응함 | 회로 신호·내부 연산 |
| 8진수 | 0~7 | 1자리와 3비트가 대응함 | 유닉스 권한 표기 |
| 10진수 | 0~9 | 자리값 합산 또는 반복 나눗셈·곱셈 | 사람이 읽는 수치 표현 |
| 16진수 | 0~9·A~F | 1자리와 4비트가 대응함 | 메모리 주소·색상·패킷 분석 |

> 요약: 8·16진수는 비트 묶음으로, 10진수는 자리값 합산이나 반복 나눗셈·곱셈으로 변환함.

### 쉽게 이해하기 (학습용)
- 2진수는 온오프 스위치, 8진수는 스위치 3개씩 묶어 읽기, 16진수는 4개씩 묶어 읽기, 10진수는 우리가 평소 쓰는 셈법이라고 보면 됨

## Ⅳ. 변환 요소 및 값 보존 구조

| 설계 요소 | 설명 |
|:---|:---|
| 원본 기수 $r_s$ | 변환 전 자리 기호의 범위와 위치 가중치 기준 |
| 목표 기수 $r_t$ | 변환 후 자리 기호의 범위와 위치 가중치 기준 |
| 자리 기호 $d_i$ | 각 위치에 놓이며 $0 \le d_i < r$를 만족하는 값 |
| 위치 가중치 $r^i$ | 정수부는 $i \ge 0$, 소수부는 $i < 0$인 자리별 배율 |
| 수치값 $\sum d_i r^i$ | 기수가 바뀌어도 동일하게 유지해야 하는 값 |

> 요약: 진법 변환은 자리 기호와 위치 가중치의 합을 기준으로 원본·목표 기수에서 같은 수치값을 보존함.

### 쉽게 이해하기 (학습용)
- 원래 쓰던 단위(원본 기수)와 바꿀 단위(목표 기수)가 있고, 각 자리 숫자에 자리별 배율(위치 가중치)을 곱해 다 더한 값이 단위를 바꿔도 항상 똑같이 유지되어야 함

## Ⅴ. 원리 및 절차 흐름도

```text
원본·목표 기수 확인 → 정수부·소수부 분리
                              ├─ 정수부 → 목표 기수로 반복 나눗셈
                              └─ 소수부 → 목표 기수로 반복 곱셈
                                           ↓
                                    역변환으로 값 확인
```

1. **진법 식별**: 원본 기수와 목표 기수를 확인하고 직접 묶음 가능 여부를 판단함
2. **부분 분리**: 정수부와 소수부를 나누어 서로 다른 변환 규칙을 적용함
3. **변환 수행**: 정수부는 나눗셈, 소수부는 곱셈, 2·8·16진수는 비트 묶음으로 처리함
4. **값 검증**: 결과를 역변환하거나 가중치 합산으로 원래 값과 비교함

> 요약: 정수부·소수부 규칙을 분리하고 역변환으로 값 보존 여부를 확인함.

### 쉽게 이해하기 (학습용)
- 정수 부분은 목표 단위로 계속 나눠 나머지를 거꾸로 읽고, 소수 부분은 계속 곱해 나온 자리를 순서대로 읽은 뒤, 다시 원래 단위로 되돌려 값이 맞는지 확인함

## Ⅵ. 실무 사례

1. 패킷 분석기는 비트 필드를 2·10·16진수로 변환해 프로토콜 헤더를 표시함
2. 수치 변환 모듈은 소수부 자릿수와 반올림 방식을 고정해 같은 입력의 변환 결과를 일관되게 유지함

### 쉽게 이해하기 (학습용)
- 네트워크 패킷을 뜯어볼 때 같은 비트값을 2진수·10진수·16진수로 바꿔가며 표시해주는 도구가 이 변환 절차를 그대로 씀

## Ⅶ. 결론

- 수 체계 변환은 값 보존을 전제로 표현만 바꾸는 절차이므로 비트 묶음 가능성과 정밀도 손실을 기준으로 변환 방식을 선택해야 함
- 프로토콜·파일 변환에서는 기수뿐 아니라 비트 폭·반올림 규칙을 계약으로 고정하고 왕복 변환을 검증해야 함

### 쉽게 이해하기 (학습용)
- 겉모습(진법)만 바꾸는 작업이라도 원래 값이 정말 보존되는지, 소수 자리가 잘리진 않는지는 변환 후 반드시 되돌려 확인해야 함
