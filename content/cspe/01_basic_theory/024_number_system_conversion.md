## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 컴퓨터 내부의 데이터 표현(2진수)과 인간의 가독성 향상(8/16진수)을 위해 서로 다른 진법 간에 수를 변환하는 과정임 |
| 배경/필요성 | 디지털 회로의 ON/OFF 상태 처리 및 메모리 주소, 기계어 코드의 효율적 표기를 위해 필요함 |
| 출제 의도 | 기수(Radix)의 개념과 진법 간 변환 알고리즘의 정확한 수행 능력 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|      Binary       | <---> |      Octal        | <---> |   Hexadecimal     |
|     (Base 2)      |       |     (Base 8)      |       |    (Base 16)      |
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 2진수 (Binary) | 0과 1만을 사용하여 데이터를 표현 (컴퓨터의 기본 언어) | 전구의 켜짐/꺼짐 |
| 8진수 (Octal) | 0~7을 사용하며, 2진수 3자리를 1자리로 묶어 표현 | 3비트 압축 포장 |
| 16진수 (Hexadecimal) | 0~9, A~F를 사용하며, 2진수 4자리를 1자리로 묶어 표현 | 4비트(니블) 묶음 |
> 요약: 수 체계는 2진수를 근간으로 하며, 표현 길이를 줄이기 위해 8진수와 16진수가 사용됨

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 진수 그룹화 | -> | 2. 자릿수 변환 | -> | 3. 중간 변환   | -> | 4. 결과 도출   |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 진수 그룹화: 2진수에서 8진수(3자리), 16진수(4자리) 변환 시 소수점을 기준으로 비트를 묶음
2. 자릿수 변환: 묶인 비트 그룹을 해당하는 8진수 또는 16진수 기호로 매핑하여 치환함
3. 중간 변환: 10진수에서 다른 진수로 변환 시, 나눗셈(정수부)과 곱셈(소수부)을 반복하여 나머지를 취함
4. 결과 도출: 산출된 기호들을 올바른 순서(정수부는 역순, 소수부는 정순)로 나열하여 최종 변환값을 완성함
> 요약: 기수에 따른 나눗셈/곱셈 연산과 비트 그룹 매핑을 통해 진법을 상호 변환함

## Ⅳ. 문제점
- 소수점 오차 발생: 10진수 소수를 2진수로 변환할 때 무한 소수가 되는 경우 정밀도 손실이 발생함
- 진법 혼동 오류: 코드나 시스템 명령어에서 8진수와 10진수, 16진수 표기(접두사) 혼동으로 인한 버그가 유발됨

## Ⅴ. 개선방안
- 부동소수점 표준 적용: 소수점 오차 해결을 위해 IEEE 754 부동소수점 표준이나 BCD(이진화 십진법) 코드를 활용함
- 명확한 접두사 명시: 프로그래밍 시 0b(2진), 0(8진), 0x(16진) 등 명확한 접두사를 사용하여 표현의 모호성을 제거함

## Ⅵ. 전망
- 기본 수 체계는 변함없이 유지될 것이나, 양자 컴퓨팅 시대에는 큐비트 상태를 표현하는 다차원 수 체계 변환 기술로 확장될 전망임
