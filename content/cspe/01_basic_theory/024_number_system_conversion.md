# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 기수(Radix)를 달리하는 수 체계 간에 수의 값을 유지하며 표현 방식을 바꾸는 것.
- **주요 진법**:
  - **2진수 (Binary)**: 0, 1 사용. 컴퓨터의 기본 언어.
  - **8진수 (Octal)**: 0~7 사용. 2진수 3자리를 한 자리로 표현.
  - **10진수 (Decimal)**: 0~9 사용. 인간이 사용하는 기본 진법.
  - **16진수 (Hexadecimal)**: 0~9, A~F 사용. 2진수 4자리를 한 자리로 표현. 메모리 주소 표기에 최적.
- **핵심 직관**: "2의 거듭제곱 관계인 진법(2, 8, 16)끼리는 산술 연산 없이 비트 그룹핑만으로 즉시 변환 가능하다."

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **기수 (Radix / Base)** | 진법의 기초가 되는 수 (2, 8, 10, 16 등) | 숫자의 종류 개수 |
| **위치적 기수법** | 숫자의 위치(자릿수)에 따라 가중치가 달라지는 방식 | 10진수 111에서 각 1의 가치는 100, 10, 1임 |
| **가중치 (Weight)** | 각 자릿수가 가지는 실제 값 ($r^n$) | $16^1=16$, $16^0=1$ |
| **LSB / MSB** | 최하위 비트 / 최상위 비트 | 숫자의 맨 오른쪽 / 맨 왼쪽 |
| **정수부 / 소수부** | 소수점 앞의 수 / 소수점 뒤의 수 | 12.34에서 12와 0.34 |

## 깊이 이해

- **10진수 $\to$ N진수 변환**: 
  - **정수부**: 기수 N으로 더 이상 나눌 수 없을 때까지 반복해서 나누고, **나머지를 역순**으로 읽습니다.
  - **소수부**: 기수 N을 계속 곱하며, **정수부로 튀어나오는 수**를 순서대로 읽습니다. (0이 될 때까지 혹은 필요한 정밀도까지)

- **2진수 $\leftrightarrow$ 8진수/16진수 (꿀팁)**: 
  - 10진수를 거치지 마세요! 
  - **2진수 $\to$ 8진수**: 소수점 기준으로 **3자리씩** 묶어서 변환.
  - **2진수 $\to$ 16진수**: 소수점 기준으로 **4자리씩** 묶어서 변환. (예: $1010_2 \to A_{16}$)

- **왜 16진수를 쓰는가?**: 
  2진수 $11111111$보다 $FF$가 훨씬 짧고 명확합니다. 특히 1바이트(8비트)는 16진수 딱 2자리($00$~$FF$)로 떨어지기 때문에 컴퓨터 메모리 주소나 색상 코드(#FFFFFF) 표기에 매우 효율적입니다.

- **소수점 변환의 함정**: 
  10진수 $0.1$은 2진수로 바꾸면 $0.000110011...$ 처럼 무한 순환 소수가 됩니다. 이것이 컴퓨터가 실수를 완벽하게 저장하지 못하고 미세한 오차가 발생하는 근본적인 원인입니다.

- **일상 비유 (동전 세기)**: 
  - 1원짜리(2진수) 1,000개를 일일이 세는 것보다, 100원짜리(8진수)나 500원짜리(16진수) 묶음으로 세는 것이 훨씬 빠르고 정확한 것과 같습니다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 기수(Radix)와 자릿수별 가중치($r^n$)를 이용한 **위치적 기수법(Positional Notation)** 원리에 기반하여 수의 표현 형태를 변환함.
> 2. **가치**: 2진수의 가독성 한계를 **8진수 및 16진수**를 통해 보완하며, 메모리 주소 및 네트워크 패킷 분석의 효율성을 극대화함.
> 3. **주의**: 10진 소수의 2진 변환 시 발생하는 **무한 순환 소수** 특성이 부동소수점 오차의 근본 원인임을 인지하고 정밀도 설계를 수행해야 함.

## Ⅰ. 수 체계의 근간, 진법 변환(Number Conversion)의 개요
### 1. 정의
- 특정 기수를 사용하는 수 표현을 다른 기수의 표현으로 값을 유지하며 변환하는 연산 과정.
### 2. 주요 진법별 특징
- **2진수 (Binary)**: 하드웨어의 전압(High/Low) 상태 직접 대응.
- **16진수 (Hexadecimal)**: 4비트를 1글자로 압축, 메모리 주소 및 바이트 단위 표기에 최적.

## Ⅱ. 정수 및 소수의 진법 변환 알고리즘
### 1. 정수부 변환 (Integer Part)
- **알고리즘**: 변환하고자 하는 기수 $r$로 몫이 0이 될 때까지 나눈 후, 나머지들을 역순으로 취합.
- **사례**: $13_{10} \to 2$로 나누면 나머지 $1, 0, 1, 1$ 발생 $\to 1101_2$.

### 2. 소수부 변환 (Fractional Part)
- **알고리즘**: 기수 $r$을 반복 곱하여 정수부로 올라오는 숫자를 순서대로 취합.
- **주의**: 10진수 유한 소수가 2진수 무한 소수가 될 수 있음 (정밀도 손실 원인).

## Ⅲ. 2진수 기반 진법 간 고속 변환 메커니즘
### 1. 비트 그룹핑 (Bit Grouping) 원리
- $2^3 = 8$ 이므로 2진수 3자리는 8진수 1자리와 1:1 대응.
- $2^4 = 16$ 이므로 2진수 4자리는 16진수 1자리와 1:1 대응.

### 2. 변환 도식 (2진수 ↔ 16진수)
```
2진수:  [1101] [0111] . [1010]
        \    /  \    /    \    /
16진수:    D      7    .    A    (D7.A)
```

## Ⅳ. 주요 진법별 가중치 및 표기법 비교
| 진법 | 기수 | 기호 | 가중치 예 (3번째 자리) | 용도 |
|:---:|:---:|:---|:---:|:---|
| 2진수 | 2 | 0, 1 | $2^2 = 4$ | 컴퓨터 내부 연산 |
| 8진수 | 8 | 0 ~ 7 | $8^2 = 64$ | 리눅스 권한 설정 |
| 10진수 | 10 | 0 ~ 9 | $10^2 = 100$ | 인간의 수 체계 |
| 16진수 | 16 | 0 ~ 9, A ~ F | $16^2 = 256$ | 메모리 주소, 색상 코드 |

## Ⅴ. 기술사 관점의 고려사항 및 실무 적용
### 1. 부동소수점 오차에 대한 이해
- 금융 시스템 등 고정밀 연산이 필요한 경우, 2진수 변환 오차를 방지하기 위해 **BCD(Binary Coded Decimal)**나 **Decimal 자료형** 사용 권장.
### 2. 데이터 표현의 압축과 가독성
- 로그 분석이나 디버깅 시 2진수 덤프(Dump)보다는 16진수 표기를 통해 데이터 패턴(Magic Number 등)을 신속히 식별.
### 3. 엔디안(Endianness) 변환 시의 주의
- 다중 바이트 데이터를 진법 변환하여 통신할 때, 바이트 저장 순서(Big/Little Endian)에 따른 값 왜곡 주의.

## Ⅵ. 기술사 관점의 결론: "데이터의 본질과 표현의 효율성"
- 수 체계 변환은 단순한 산술을 넘어, **기계의 언어(2진수)와 인간의 인지(10/16진수)**를 연결하는 핵심 인터페이스임.
- 아키텍트는 각 진법의 특성을 이해하여 **데이터 저장 효율과 연산의 정확성** 사이의 균형을 맞춘 최적의 수 체계 설계를 수행해야 함.
