## Ⅰ. 개요
- **정의**: 위치 기수법 기반으로 10진·2진·8진·16진 수를 상호 변환하는 기법
- **배경/필요성**: 컴퓨터는 2진 체계로 동작하나, 사람은 10진을 사용하므로 양쪽 간 정확한 변환 규칙이 필요함. 8진·16진은 2진의 축약 표기로 주소·색상코드 등에 활용됨
- **비유**: 같은 무게를 kg·lb·oz로 바꿔 표기하는 단위 환산과 동일한 원리

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기수 변환 원리와 실무 적용력 검증 | 정수부(나눗셈)·소수부(곱셈) 변환 절차, 2진↔8진·16진 그룹 매핑 | 소수부 변환 시 무한 반복 가능성 언급, BCD와 일반 2진 혼동 금지 |

> 요약: 위치 기수법의 가중치 원리를 바탕으로 진법 간 수치를 정확히 변환하는 기법임

## Ⅱ. 구성요소
```text
+------------------+
| 위치 기수법 원리  |
| (자릿값 = 기수^위치) |
+--------+---------+
         |
    +----+----+----+
    |    |    |    |
    v    v    v    v
  2진  8진  10진  16진
  (B)  (O)  (D)   (H)
    |    |         |
    +----+---------+
    3bit   4bit 그룹 매핑
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 기수(Radix) | 한 자릿수가 표현할 수 있는 기호 개수(2, 8, 10, 16) | 시계의 눈금 간격(12시간 vs 24시간) |
| 자릿값(Positional Weight) | 각 자리의 가중치로 `기수^위치`로 계산됨 | 화폐에서 1원·10원·100원 자리 |
| 정수부 변환(나눗셈법) | 10진 정수를 목표 기수로 반복 나누어 나머지를 역순 배열함 | 큰 묶음을 작은 단위로 쪼개는 과정 |
| 소수부 변환(곱셈법) | 10진 소수를 목표 기수로 반복 곱하여 정수부를 순서대로 취함 | 남은 잔돈을 큰 단위로 올려 세는 과정 |
| BCD(Binary Coded Decimal) | 10진 각 자릿수를 독립적으로 4비트 2진으로 인코딩함 | 각 숫자칸마다 개별 이진 이름표를 붙이는 방식 |
| 그레이 코드(Gray Code) | 인접 값 간 1비트만 변화하도록 배열된 2진 코드 | 회전 다이얼에서 한 칸 돌릴 때 한 접점만 바뀌는 구조 |

> 요약: 기수·자릿값·변환법(나눗셈/곱셈)·특수 코드(BCD/그레이)가 핵심 구성임

## Ⅲ. 절차
```text
10진 정수 --> 나눗셈 반복 --> 나머지 역순 --> 목표 진법 정수부
10진 소수 --> 곱셈 반복   --> 정수부 순차 --> 목표 진법 소수부
2진 <---> 8진: 3비트 그룹 매핑
2진 <---> 16진: 4비트 그룹 매핑
```
- 1단계: 변환 대상 수를 정수부와 소수부로 분리함
- 2단계: 정수부는 목표 기수로 반복 나눗셈하여 나머지를 역순으로 나열함 (예: `13 / 2` → 나머지 `1`, `6 / 2` → 나머지 `0`, ... → `1101`)
- 3단계: 소수부는 목표 기수로 반복 곱셈하여 매 단계 정수부를 순서대로 취함 (예: `0.625 * 2` = `1.25` → `1`, `0.25 * 2` = `0.5` → `0`, ... → `.101`)
- 4단계: 2진↔8진은 3비트, 2진↔16진은 4비트 단위로 그룹화하여 직접 매핑함

> 요약: 정수부 나눗셈·소수부 곱셈·비트 그룹 매핑 세 가지 절차로 진법을 변환함

## Ⅳ. 문제점
- 소수부 무한 반복: 10진 소수 중 목표 기수에서 유한 표현이 불가능한 값이 존재함 — `0.1`(10진)은 2진에서 `0.0001100110011...`로 무한 반복되어 정밀도 손실이 발생함
- BCD 공간 낭비: 4비트 중 6개 코드(`1010`~`1111`)가 미사용됨 — 동일 값 표현에 순수 2진 대비 약 20% 추가 비트가 필요함
- 수동 변환 오류: 그룹 경계 정렬 시 패딩 누락이 빈번함 — 2진 `10111`을 8진 변환 시 `010 111`로 좌측 0 패딩을 빠뜨리면 오답이 됨

> 요약: 소수부 무한 반복·BCD 공간 낭비·그룹 패딩 실수가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 소수부 변환 시 유효 비트 수를 명시하고 반올림 정책(025 참조)을 적용하여 정밀도 손실 범위를 통제함
2. 중기: BCD 대신 Densely Packed Decimal(DPD) 인코딩을 사용하여 10비트에 3자리(0~999)를 압축 저장함
3. 장기: 자동 검증 도구(비트 시각화·역변환 검증 루틴)를 교육·실무에 도입하여 수동 변환 오류를 체계적으로 제거함

> 요약: 반올림 정책 적용 → DPD 압축 → 자동 검증 도구 순으로 문제를 해소함

## Ⅵ. 전망
- 발전 방향: IEEE 754-2019의 10진 부동소수점(decimal floating-point) 표준 확산으로 BCD/DPD 기반 하드웨어 연산 수요가 증가함
- 기술사적 판단: 진법 변환은 컴퓨터 구조·네트워크 주소·색상 표현 등 전 분야의 기초이므로 원리 수준의 이해가 지속적으로 요구됨
- 기술사 제언: 정밀도가 중요한 금융·과학 연산에서는 2진 부동소수점 한계를 인지하고 10진 연산 라이브러리 또는 하드웨어 활용을 검토할 필요가 있음
