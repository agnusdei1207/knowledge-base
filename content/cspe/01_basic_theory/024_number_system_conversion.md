# 024. 수 체계 변환 — 이진·8진·16진 (Number System Conversion) [출제: -]

## 미리 알고가기

- **기수 (Radix, Base)**: 숫자를 표현하는 기초가 되는 수이며, 각 자릿수가 가지는 가중치($Base^n$)를 결정함
- **보수 (Complement)**: 어떤 수와 더했을 때 다음 자릿수로 넘어가게 하거나, 특정 수($r$ 또는 $r-1$)가 되게 하는 '보충해주는 수'임
- **비트 (Bit)**: 정보의 최소 단위($0$ 또는 $1$)이며, $4$비트가 모여 $16$진수 한 자리를 형성함

## Ⅰ. 개요

- **정의/개념**: 진법 변환은 동일한 수치를 다른 기수법($2$, $8$, $10$, $16$진수 등)으로 표현하는 과정이며, 보수는 컴퓨터가 가산기만을 이용하여 감산(뺄셈)을 수행하기 위해 도입한 수의 표현 방식임
- **배경/필요성**: 컴퓨터 하드웨어는 $2$진 체계로 동작하지만, 사람은 $10$진수나 가독성이 높은 $16$진수를 선호함. 또한 CPU 내 회로 구성을 단순화하기 위해 뺄셈을 '음수의 덧셈'으로 치환하여 처리할 필요가 있어 보수 개념이 필수적임

## Ⅱ. 특징 및 비교

기수 변환은 주로 $2$의 거듭제곱 간의 묶음 처리가 핵심이며, 보수는 기수($r$) 보수와 기수-1($r-1$) 보수로 구분됨.

| 비교 항목 | $2$진수 (Binary) | $8$진수 (Octal) | $16$진수 (Hex) | $10$진수 (Decimal) |
|:---|:---|:---|:---|:---|
| **기수 ($r$)** | $2$ | $8$ ($2^3$) | $16$ ($2^4$) | $10$ |
| **비트 대응** | $1$비트 | **$3$비트 묶음** | **$4$비트 묶음** | 대응 안 됨 |
| **주요 용도** | 논리 회로 저장 | 파일 권한(rwx) | **주소, 덤프 출력** | 실생활 수량 |

| 보수 유형 | $1$의 보수 (1's Complement) | $2$의 보수 (2's Complement) |
|:---|:---|:---|:---|
| **생성 방법** | 모든 비트를 반전 (NOT) | $1$의 보수에 $1$을 더함 |
| **0의 표현** | $+0$, $-0$ 두 가지 존재 (모호함) | **$0$이 하나로 유일함** |
| **연산 이점** | 단순 반전으로 구현 쉬움 | **감산 회로 불필요 (가산기 통합)** |
| **표현 범위** | $-2^{n-1}+1 \sim 2^{n-1}-1$ | **$-2^{n-1} \sim 2^{n-1}-1$ (하나 더 넓음)** |

> 요약: 현대 컴퓨터는 $0$의 표현이 명확하고 연산 효율이 높은 **$2$의 보수** 방식을 표준으로 채택함.

## Ⅲ. 구성요소/구조

진법 변환은 정수부와 소수부의 처리 방식이 다르며, 보수 연산은 '가산기를 통한 감산'이 핵심 구조임.

- **변환 방식**:
  - **정수부**: 대상 기수($r$)로 계속 나누어 나머지를 역순으로 읽음
  - **소수부**: 대상 기수($r$)를 계속 곱하여 정수 부분을 순서대로 읽음
  - **$2$진 $\leftrightarrow$ $16$진**: 소수점을 기준으로 $4$비트씩 끊어서 $1:1$ 매핑 ($1011_2 \rightarrow B_{16}$)

- **보수를 이용한 뺄셈 구조 (원리/흐름도)**:

```text
[Subtraction: A - B] -> [Complement: A + (-B)]
1. 감수(B)를 2의 보수로 변환 (반전 후 +1)
2. 피감수(A)와 변환된 보수(-B)를 더함
3. 최상위 비트(MSB)의 올림수(Carry) 발생 시:
   - 양수 결과, Carry는 버림 (2의 보수 기준)
4. 결과값의 MSB가 1이면 음수, 0이면 양수 판정
```

1. **정수 변환**: $10$진수 $13$을 $2$진수로 변환 시 $2$로 나누어 나머지 $1101$ 도출
2. **보수 생성**: $0011(3)$의 $2$의 보수는 $1100 + 1 = 1101(-3)$
3. **가산 수행**: $0101(5) + 1101(-3) = (1)0010 \rightarrow 0010(2)$ 도출 (Carry 무시)

## Ⅳ. 문제점 및 개선방안

1. **부동소수점 변환 오차**: $10$진수 소수($0.1$ 등)를 $2$진수로 변환 시 무한 소수가 되어 정확한 값 표현이 불가능함
   - **개선방안**: IEEE 754 표준 부동소수점 방식을 사용하여 정밀도를 관리하거나, 금융 연산 등에서는 정수 기반의 고정소수점 방식을 사용함 (확인: 유효 자릿수 및 오차 한계)

2. **오버플로우 (Overflow) 발생**: 두 양수를 더했는데 결과가 음수가 되거나, 표현 범위를 벗어나는 연산 오류 발생
   - **개선방안**: 연산 결과의 MSB(최상위 비트)와 Carry를 비교하여 오버플로우 플래그를 체크하고 예외 처리를 수행함 (확인: 연산 결과의 부호 일관성)

3. **진법 변환의 가독성 저하**: 긴 $2$진 비트열은 사람이 분석하기 어려워 디버깅 효율을 떨어뜨림
   - **개선방안**: 로우레벨 데이터 분석 시 항상 $16$진수(Hex) 덤프를 병행 표기하여 $4$비트 단위의 가독성을 확보함 (확인: 덤프 출력의 직관성)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 메모리 주소 체계 | $32$/$64$비트 주소값을 $16$진수로 표기하여 메모리 맵 관리 및 포인터 연산 수행 | 주소 오정렬(Alignment) 여부 |
| IP 주소 (IPv4/v6) | $32$비트 $2$진 주소를 $8$비트씩 끊어 $10$진수(v4)나 $16$진수(v6)로 변환하여 할당 | 서브넷 마스크 일치 여부 |
| 이미지/색상 (RGB) | 각 색상 채널($8$비트)을 $16$진수 두 자리(`#FFFFFF`)로 결합하여 색상 정보 정의 | 색상 표현 정밀도 ($24$/$32$비트) |
| 어셈블리 연산 | `SUB` 명령어를 내부적으로 $2$의 보수 가산기로 처리하여 CPU 회로 최적화 | 연산 사이클 수, 전력 소모량 |

> 요약: 기계와 인간 사이의 데이터 교환 및 CPU 연산 최적화의 근간이 되는 수치 체계임.

## Ⅵ. 결론

진법 변환과 보수 이론은 디지털 컴퓨터의 '언어'와 '연산 방식'을 규정하는 원자 단위의 지식임. 기술사는 단순히 변환 공식을 암기하는 것을 넘어, 왜 $2$의 보수가 표준이 되었는지, 그리고 진법 변환 과정에서 발생하는 소수점 오차가 시스템 전체에 어떤 영향을 미칠 수 있는지에 대한 공학적 안목을 가져야 함.

특히 임베디드 시스템이나 커널 개발과 같은 로우레벨 영역에서는 비트 단위의 데이터 해석 능력이 필수적이므로, 진법 간의 자유로운 변환과 보수 연산의 원리를 명확히 숙지하여 하드웨어 자원을 효율적으로 제어할 수 있어야 함. 결국 수 체계의 깊은 이해는 데이터의 본질을 파악하고 오류 없는 시스템을 설계하는 출발점임.
