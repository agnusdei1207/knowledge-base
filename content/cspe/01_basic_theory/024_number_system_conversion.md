## 미리 알고가기

- 기수(Base): 한 자리에서 사용할 수 있는 숫자의 개수이며 2진수는 2, 10진수는 10임
- 자리값: 각 자리 숫자에 기수의 거듭제곱을 곱해 실제 값을 계산하는 기준임
- 정수부 변환: 목표 기수로 반복 나눗셈을 수행하고 나머지를 역순으로 읽음
- 소수부 변환: 목표 기수를 반복 곱하고 정수부를 순서대로 읽음
- 16진수: 2진수 4비트를 한 자리로 묶어 메모리 주소와 비트 패턴을 간결하게 표현함

## Ⅰ. 개요

- **정의**: 수 체계 변환은 동일한 수량을 2진, 8진, 10진, 16진처럼 서로 다른 기수의 자리값 기준으로 다시 표현하는 방법이며, 인간이 읽는 수와 컴퓨터가 처리하는 비트 표현을 연결하기 위해 사용함.
- **배경/필요성**: 디지털 회로는 0과 1로 값을 저장하지만 설계자와 운영자는 주소, 마스크, 오류 코드를 10진수나 16진수로 해석하므로 정확한 변환 절차가 필요함.
- **비유**: 같은 금액을 원화, 달러, 동전 묶음처럼 단위만 바꾸어 표현하는 과정과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기수와 자리값 원리 설명 | 가중치 합, 반복 나눗셈, 반복 곱셈 | 정수부와 소수부 절차 혼동 |
| 컴퓨터 표현과 연결 | 2진-8진-16진 묶음 변환, 보수 표현 연계 | 16진수를 단순 축약 표기로만 설명 |

> 요약: 수 체계 변환은 자리값 기준을 바꾸어 같은 값을 다른 기수로 표현하고, 비트 단위 해석과 사람 친화적 표기를 연결함.

## Ⅱ. 특징/비교

| 판단 기준 | 10진수 중심 표현 | 2진·8진·16진 표현 |
|:---|:---|:---|
| 처리 주체 | 사람이 계산하고 읽기 쉬움 | 컴퓨터 저장·연산·주소 표현에 적합함 |
| 자리값 기준 | 10의 거듭제곱으로 값을 해석함 | 2의 거듭제곱과 비트 묶음으로 값을 해석함 |
| 변환 비용 | 하드웨어 비트 구조와 직접 대응하지 않음 | 8진은 3비트, 16진은 4비트 단위로 직접 대응함 |
| 선택 기준 | 보고서, 화면 표시, 일반 계산에 적합함 | 메모리, 레지스터, 네트워크 마스크 해석에 적합함 |

- **정수 기준**: 나눗셈 나머지를 역순으로 읽어 목표 기수의 자리값을 결정함.
- **소수 기준**: 곱셈 결과의 정수부를 순서대로 읽되 일부 값은 유한 비트로 끝나지 않을 수 있음.
- **비트 기준**: 2진수를 3비트 또는 4비트로 묶으면 8진수·16진수 변환을 빠르게 수행할 수 있음.

> 요약: 변환 방법은 대상이 정수부인지 소수부인지, 그리고 목표 기수가 2의 거듭제곱인지에 따라 달라짐.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Source     | ---> | Positional | ---> | Target     |
| Number     |      | Value      |      | Number     |
+------------+      +------------+      +------------+
       |                   |
       v                   v
+------------+      +------------+
| Integer    |      | Fractional |
| Part       |      | Part       |
+------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 원천 기수 | 변환 전 수를 해석하는 기준이며 각 자리 가중치를 결정함 | 현재 통화 단위 |
| 목표 기수 | 변환 후 표현할 기준이며 나눗셈이나 곱셈의 기준값이 됨 | 바꿀 통화 단위 |
| 자리값 가중치 | 각 자리 숫자에 기수의 거듭제곱을 곱해 실제 값을 계산함 | 자릿수별 무게 |
| 정수부 처리 | 목표 기수로 반복 나누어 나머지를 모아 표현함 | 큰 묶음으로 나누기 |
| 소수부 처리 | 목표 기수를 반복 곱해 정수부를 차례로 추출함 | 작은 조각으로 쪼개기 |

> 요약: 수 체계 변환은 원천 기수의 자리값을 실제 값으로 해석한 뒤 목표 기수의 정수부와 소수부 자리로 재배치하는 구조임.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Split      | ---> | Convert    | ---> | Convert    | ---> | Combine    |
| Number     |      | Integer    |      | Fraction   |      | Result     |
+------------+      +------------+      +------------+      +------------+
```

1. **수 분리**: 변환할 값을 정수부와 소수부로 나누고 원천 기수와 목표 기수를 확인함.
2. **정수부 변환**: 정수부를 목표 기수로 반복 나누고 나머지를 역순으로 배열함.
3. **소수부 변환**: 소수부에 목표 기수를 반복 곱하고 각 단계의 정수부를 순서대로 기록함.
4. **결과 검증**: 변환 결과를 다시 원천 기수로 환산해 값이 일치하는지 확인하고 반복 소수는 정밀도를 명시함.

> 요약: 정수부는 나눗셈 역순, 소수부는 곱셈 순서로 변환하며 마지막에 원값 환산으로 오류를 검증함.

## Ⅴ. 문제점

- **P1 소수 표현 한계**: 0.1 같은 일부 10진 소수는 2진수에서 무한 반복되어 유한 비트로 정확히 표현되지 않음.
- **P2 자리수·부호 혼동**: 16진 표기만 보고 비트 폭과 부호 표현을 모르면 같은 패턴을 다른 값으로 해석할 수 있음.
- **P3 수작업 오류**: 나머지 역순 읽기, 소수부 곱셈 순서, 2진 묶음 경계에서 계산 실수가 발생하기 쉬움.

> 요약: 수 체계 변환의 핵심 위험은 소수 정밀도, 비트 폭 해석, 절차 순서 오류임.

## Ⅵ. 개선방안

- **P1 대응**: 유한 표현 가능 여부를 확인하고 반복 소수는 반올림 자리수와 오차 범위를 함께 기록함. (확인: 재환산 오차)
- **P2 대응**: 변환값마다 비트 폭, signed/unsigned, 보수 표현 여부를 명시함. (확인: 동일 비트 패턴 해석표)
- **P3 대응**: 정수부·소수부 절차를 분리해 쓰고 2진-16진 변환은 4비트 패딩 후 묶음 단위로 검산함. (확인: 원기수 역변환)

> 요약: 변환 결과에는 정밀도와 비트 해석 조건을 함께 붙이고, 역변환 검산으로 절차 오류를 줄여야 함.

## Ⅶ. 전망

- **발전 방향**: 임베디드, 네트워크 주소, 보안 키, 디버깅 로그 해석에서 2진·16진 변환 능력은 자동 도구와 결합되더라도 기본 검산 역량으로 계속 요구됨.
- **설계 관점**: 값만 변환하지 말고 비트 폭, signed/unsigned, 소수 정밀도, 패딩 조건을 함께 정의해야 시스템 간 해석 차이를 줄일 수 있음.
- **검증 관점**: 원기수 역변환, 4비트 묶음 검산, 소수부 오차 범위 확인으로 변환 절차와 표현 손실을 분리해 확인해야 함.
- **운영 관점**: 로그·패킷·레지스터 덤프 해석 시 표기 접두어, endian, 마스크 기준을 표준화해 장애 분석 결과의 일관성을 유지해야 함.
- **적용 관점**: 주소·권한 비트·장치 레지스터 해석에는 필수이나, 금액·정밀 계산에는 10진 decimal이나 고정소수점 선택을 검토해야 함.
- **보안·신뢰 관점**: 권한 비트, 키 길이, 마스크 값은 변환 오류가 접근통제 실패로 이어질 수 있으므로 경계값과 자리수 누락을 별도 점검해야 함.
- **기술사 제언**: 답안에서는 기수 변환 절차를 IEEE 754, 2의 보수, IP 마스크 해석과 연결해 값·폭·정밀도 판단을 함께 제시해야 함.
