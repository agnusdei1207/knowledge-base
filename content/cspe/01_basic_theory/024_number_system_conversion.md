## Ⅰ. 개요
- 정의: 숫자를 표현하는 기수(Radix)를 서로 다른 진법으로 변환하는 기법임
- 배경/필요성: 컴퓨터 내부 처리(2진), 가독성(16진), 메모리 주소 표현 등에 사용됨
- 출제 의도: 진법 변환의 원리 및 정수/소수부 변환 정확도 측정

## Ⅱ. 구성요소
- ASCII 구조도
  (10진수) <--> (2진수) <--> (8진수 / 16진수)
     |            |             |
   나눗셈      3bit/4bit      그룹화
   곱셈        묶기/풀기      치환

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 기수 (Radix) | 수 체계를 구성하는 기본 숫자의 개수 | 언어의 알파벳 |
| 자릿값 (Weight) | 진법에 따른 각 위치의 가중치(r^n) | 계급의 가치 |
| 그룹화 | 2진수를 3개(8진) 또는 4개(16진)씩 묶음 | 번들 포장 |
| 소수점 변환 | 소수부에 기수를 곱하여 정수부를 추출함 | 거스름돈 계산 |
> 요약: 수 체계 변환은 위치 기수법의 원리를 이용하여 데이터 표현 방식을 바꾸는 것임

## Ⅲ. 절차
- ASCII 흐름도
  [10진 정수] -> (기수로 반복 나눗셈) -> [나머지 역순 나열] -> [N진수]

1. 10진 -> N진: 정수부는 N으로 나누고, 소수부는 N을 곱하여 변환함
2. N진 -> 10진: 각 자릿수에 자릿값(r^n)을 곱하여 합산함
3. 2진 -> 8/16진: 소수점 기준 좌우로 3/4비트씩 묶어 대응 숫자로 치환함
4. 8/16진 -> 2진: 각 숫자를 3/4비트의 이진수로 각각 풀어서 나열함
> 요약: 2의 거듭제곱 진법 간에는 비트 그룹화를 통해 신속하게 변환 가능함

## Ⅳ. 문제점
- 정밀도 손실: 10진수 소수가 2진수에서 무한 소수가 되어 오차 발생함
- 가독성 저하: 2진수는 자릿수가 너무 길어져 인간이 직관적으로 이해하기 어려움

## Ⅴ. 개선방안
- 16진수 활용: 2진수 4비트를 한 문자로 요약하여 가독성과 효율성을 동시에 확보함
- BCD 코드: 10진수 한 자리를 4비트로 고정 표현하여 오차 없는 연산 지원함

## Ⅵ. 전망
- 저수준 시스템 제어: 리눅스 커널, 임베디드 드라이버 개발에서 메모리 맵 및 레지스터 직접 제어를 위한 16진수 기반 프로그래밍 역량이 필수적임
- 데이터 표현 최적화: 네트워크 패킷 분석 및 바이너리 프로토콜 설계 시, 데이터 오버헤드를 최소화하기 위한 진법 간 효율적 변환 기술이 요구됨
- CSF: 소수점 변환 시 발생하는 반올림 오차를 제어하기 위한 수치 해석적 접근과 가독성 향상을 위한 규격화된 표현법(Prefix 0x 등) 준수가 중요함
