# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 수 체계 변환은 **기수(Radix)**와 **가중치(Weight)**를 기반으로 10진수(Decimal)·2진수(Binary)·8진수(Octal)·16진수(Hexadecimal) 간에 수의 값을 유지하며 표현 형태를 교환하는 수학적 알고리즘이다.
- **왜 필요한가**: 컴퓨터 하드웨어는 2진수(0/1)만 처리하지만 2진수는 자릿수가 길어 인간 판독이 어려우므로, 2진수를 3비트(8진수)·4비트(16진수) 단위로 압축해 메모리 주소·네트워크 패킷 등을 효율적으로 표기해야 한다.
- **핵심 직관**: 2^3 = 8, 2^4 = 16이므로, 2진수 3자리는 8진수 1자리로, 2진수 4자리는 16진수 1자리로 산술 연산 없이 1:1 치환된다.

## 핵심 용어 정리 (내부에 등장하는 것들)

수 체계 변환의 핵심 구성 요소를 세운다. 음수 표현은 026(2의 보수), 실수 표현은 025(IEEE 754) 참조.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 기수 (Radix/Base) (상위 키워드) | 수를 표현하는 데 사용하는 기호 개수이자 자리올림 기준값 | 10진수 기수=10, 2진수 기수=2 |
| 가중치 (Weight) | 각 자리에 부여되는 기수의 거듭제곱(r^n) | 10진수 352에서 3의 가중치는 10^2 = 100 |
| 위치적 기수법 | 같은 기호라도 위치(자리)에 따라 값이 달라지는 수 표현 체계 | 10진수 303의 첫 3은 300, 마지막 3은 3 |
| 2진수 (Binary) | 기수 2, 기호 {0, 1} | 논리 게이트·ALU의 연산 단위 |
| 8진수 (Octal) | 기수 8, 기호 {0-7}, 2진수 3자리 = 8진수 1자리 | Unix 파일 권한 chmod 755 |
| 16진수 (Hexadecimal) | 기수 16, 기호 {0-9, A-F}, 2진수 4자리 = 16진수 1자리 | 메모리 주소 0x7FFF, 색상 코드 #FF0000 |
| MSB / LSB | 최상위 비트(Most Significant Bit) / 최하위 비트(Least Significant Bit) | 2진수 첫 자리 / 마지막 자리 |

## 깊이 이해
- **배경·문제의식**: 10진수 255를 2진수로 쓰면 11111111(8자리)이다. 32비트 주소를 2진수로 나열하면 32자리가 되어 인간 판독이 사실상 불가능하다. 이를 4비트씩 끊어 16진수로 표기하면 FF(2자리)로 극도로 압축된다.
- **작동 원리**:
  - **10진수 → 2진수 (정수부)**: 몫이 0이 될 때까지 2로 나누고, 나머지를 역순(LSB→MSB)으로 취합한다. 예: 13 → 13÷2=6…1, 6÷2=3…0, 3÷2=1…1, 1÷2=0…1 → 1101₂
  - **10진수 → 2진수 (소수부)**: 소수에 2를 반복 곱해 정수부로 올라오는 값을 순서대로 읽는다. 예: 0.625 → 0.625×2=1.25(1), 0.25×2=0.5(0), 0.5×2=1.0(1) → .101₂
  - **2진수 ↔ 8진수/16진수**: 소수점을 기준으로 2진수를 3자리(8진수) 또는 4자리(16진수)씩 묶고, 남는 빈칸은 0으로 패딩한 뒤 각 묶음을 해당 진수의 기호로 치환한다.
  - **N진수 → 10진수**: 각 자리 기호에 해당 위치의 가중치(r^n)를 곱해 합산한다(다항식 전개). 예: 1A₁₆ = 1×16¹ + 10×16⁰ = 26₁₀
- **비유**: 동전(2진수) 100개를 그대로 들고 다니면 불편하지만, 1000원권(16진수)으로 교환하면 지갑이 얇아진다 — 동전의 총액(값)은 변하지 않는다.
- **구체 예시**: 10.625₁₀ 변환 — 정수 10 = 1010₂, 소수 0.625 = .101₂ → 1010.101₂ → 16진수 4자리씩 묶기: 1010.1010 → A.A₁₆
- **흔한 오해·주의점**:
  - **10진 소수의 무한 순환**: 10진수 0.1은 2진수로 0.000110011…₂ (무한 반복)이므로 유한 비트로 정확히 표현할 수 없다 — 이것이 부동소수점 오차의 근본 원인이다(025 참조).
  - **비효율적 2단계 변환**: 2진수↔16진수를 10진수를 거쳐 변환하는 것은 불필요한다. 2^4 = 16 관계로 4비트 그룹핑만으로 직접 변환 가능하다.

## 연결 개념
- **부동소수점 IEEE 754 (025)**: 실수를 2진수로 저장하는 표준 — 소수부 변환 시 무한 순환 오차가 발생하는 원리를 024에서 다룸.
- **2의 보수 (026)**: 음수 정수를 2진수로 표현하는 방법.
- **논리 게이트·부울 대수 (027)**: 2진수가 하드웨어에서 처리되는 논리 연산의 기초.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 수 체계 변환은 기수(Radix)와 가중치(Weight) 기반의 위치적 기수법에서 10진·2진·8진·16진 간 값을 보존하며 표현 형태를 교환하는 알고리즘임.
> 2. **가치**: 2^n 관계의 진법(2·8·16진) 간에는 비트 그룹핑만으로 산술 연산 없이 직접 변환이 가능해 메모리 주소·패킷 분석의 표기 효율을 극대화함.
> 3. **판단 포인트**: 10진 소수의 2진 변환 시 무한 순환 소수가 발생해 잘림 오차가 불가피하므로, 금융 등 정밀도 민감 도메인은 BCD·Decimal 연산으로 우회해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 위치적 기수법의 수학적 원리 | 기수·가중치·다항식 전개(N = Σ a_i × r^i) | 변환 계산만 나열하고 가중치 원리 누락 |
| 2·8·16진수 간 변환 효율성 | 2^3=8, 2^4=16에 의한 비트 그룹핑 직접 변환 | 2진→10진→16진 비효율적 2단계 경유 서술 |
| 소수 변환의 정밀도 한계 | 10진 유한 소수의 2진 무한 순환 → 잘림 오차 | "실수 변환이 항상 정확하다"고 단정 |

> 요약: 기수·가중치 원리와 비트 그룹핑 직접 변환을 설명하고, 소수 변환 시 무한 순환으로 인한 정밀도 한계까지 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 기수(Radix)와 가중치(r^n)를 기반으로 진법 간 수의 값을 보존하며 표현 형태를 교환하는 연산 규칙임
- 배경: 하드웨어는 2진수만 처리하나 인간은 10진수에 익숙하며, 32비트 이상의 2진수 비트열은 판독이 불가능함
- 필요성: 메모리 덤프·네트워크 패킷(MAC·IPv6)·디버깅 인터페이스에서 16진수 압축 표기로 가독성과 분석 효율 확보가 필수임

## Ⅱ. 구조 및 구성요소
선형 구조도 (위치적 기수법 원리):

    값(N) = Σ a_i × r^i (i = n ~ -m)
    기호(a_i) × 가중치(r^i) 의 합산 -> 어떤 기수에서든 동일한 값

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 기수 (Radix, r) | 수 체계의 기준값, 사용 가능한 기호 개수 | r=2(Binary), r=8(Octal), r=10(Decimal), r=16(Hex) |
| 가중치 (Weight, r^i) | 자리 위치(i)에 따라 기호에 곱해지는 승수 | 좌측은 양수 승(r^n), 우측은 음수 승(r^-m) |
| 기호 (Digit, a_i) | 해당 기수에서 허용되는 숫자·문자 집합 | 16진수는 10~15를 A~F로 표기 |

> 요약: 모든 진법은 기호 × 가중치의 다항식 합산이라는 동일 구조를 공유하며, 기수만 달라질 뿐 값은 보존됨.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (진법 상호 변환):

    10진수 -> (정수: ÷r 반복·나머지 역순, 소수: ×r 반복·정수부 순서) -> 2진수 -> (4비트 그룹핑) -> 16진수
    N진수 -> (각 자리 × r^i 합산) -> 10진수

1. 10진→2진(정수): 10진 정수를 몫이 0이 될 때까지 2로 나누고 나머지를 역순(MSB→LSB)으로 취합함
2. 10진→2진(소수): 10진 소수에 2를 곱해 정수부로 올라오는 값을 순서대로 읽음 — 0이 되지 않으면 무한 반복(잘림 필요)
3. 2진↔8/16진(그룹핑): 소수점 기준 좌/우로 3자리(8진) 또는 4자리(16진)씩 묶고 부족분은 0으로 패딩 후 기호 치환
4. N진→10진(다항식): 각 자리 기호에 해당 가중치(r^i)를 곱해 모두 합산함

> 요약: 10진수와의 변환은 나눗셈·곱셈 다항식 연산이며, 2·8·16진수 상호 변환은 비트 그룹핑만으로 산술 연산 없이 직접 변환됨.

## Ⅳ. 특징
- 2^n 기수 간 호환: 기수가 2^n 관계인 진법(2·8·16진) 간에는 산술 연산 없이 비트 단위 치환만으로 즉시 변환 가능함
- 16진수 압축률: 1바이트(8비트) = 16진수 2자리로 정확히 대응하여 메모리 덤프·MAC 주소 표기에 최적화됨
- 소수부 정밀도 한계: 10진수 0.1 같은 유한 소수가 2진수에서는 0.000110011…₂ 무한 순환이 되어 잘림(Truncation) 오차가 발생함 — 025(IEEE 754) 참조

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 2진수 (Binary) | 8진수 (Octal) | 16진수 (Hexadecimal) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 기호 수 | 2 (0, 1) | 8 (0~7) | 16 (0~9, A~F) | 하드웨어 직접 대응 vs 인간 판독성 |
| 1바이트 표기 | 8자리 | 약 2.7자리 | 2자리 | 표기 길이·가독성 |
| 주요 용도 | 논리 게이트·ALU 연산 | Unix 권한(chmod) | 메모리 주소·IPv6·색상 코드 | 저수준 연산 vs 모니터링·로깅 |
| 2진 변환 | 직접 | 3비트 그룹핑 | 4비트 그룹핑 | 비트 단위 정렬 편의 |

> 요약: 연산은 2진수로 수행하되, 인간 인터페이스(디버깅·로깅·주소)는 16진수로 표기하여 가독성을 극대화함.

**리스크·대응:**
- 부동소수점 무한 순환 오차: 10진 소수의 2진 변환 시 정밀도 손실로 금융 연산 오류 발생 → BCD 인코딩 또는 언어 내장 Decimal 객체(Java BigDecimal, Python decimal) 사용 (지표: 금융 데이터 오차율 0%)
- 엔디안(Endianness) 불일치: 16진수 바이트열의 메모리 저장 순서가 CPU 아키텍처(x86: Little Endian, ARM: 설정 가능)마다 다름 → 네트워크 통신 시 Big Endian(Network Byte Order)으로 표준화 (지표: 패킷 파싱 오류율 0%)

**점검 지표:**
- 변환 정확성: 크로스 플랫폼 데이터 교환 시 진법 변환·엔디안 변환의 무결성 — 테스트 벡터 검증
- 정밀도 준수: 금융·과학 연산에서 요구 유효 자릿수 내 오차 수렴 여부 — 기준 대비 오차율 측정

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 메모리·네트워크 덤프 분석: Wireshark·GDB에서 패킷 페이로드와 메모리 주소를 16진수 덤프로 출력해 분석가 가독성을 확보함
2. 비트 마스킹 최적화: 파일 권한(chmod 755)·플래그 레지스터 제어 시 8/16진수를 OR/AND 비트 마스크로 활용해 연산 사이클을 절약함
3. 금융 시스템 정밀도 보장: 진법 변환 오차(부동소수점)를 원천 차단하기 위해 BCD 또는 Decimal 라이브러리를 금융 코어에 필수 도입함

**결론:**
- 기술사 판단: 진법 변환은 단순 수학이 아니라, 하드웨어의 2진 연산과 인간의 10진 인지를 16진수로 연결하는 핵심 아키텍처 인터페이스이며, 소수 변환의 정밀도 한계를 인지한 도메인별 대안 설계가 필수임
- 향후 방향: 양자 컴퓨팅의 큐비트(0과 1의 중첩)가 기존 2진 논리를 확장하며, AI 추론의 저정밀 연산(FP8·INT4)이 새로운 수 표현 체계를 요구하고 있음
