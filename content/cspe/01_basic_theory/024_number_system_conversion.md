## 미리 알고가기

- 기수(Radix/Base): 한 자릿수를 표현하기 위해 사용하는 고유한 숫자의 개수임 (예: 2진수는 0~1, 16진수는 0~9, A~F)
- 가중치(Weight): 숫자의 위치에 따라 결정되는 값의 크기로, 소수점을 기준으로 왼쪽은 기수의 양의 거듭제곱($r^k$), 오른쪽은 음의 거듭제곱($r^{-k}$)을 곱함
- 그룹핑(Grouping): 2진수를 8진수나 16진수로 변환할 때, 비트들을 일정 개수(3개 또는 4개)씩 묶어 처리하는 기법임
- 비트(Bit): 정보 표현의 최소 단위이며, $2^n$개의 상태를 표현하기 위해 $n$개의 비트가 필요함

## Ⅰ. 개요

- **정의/개념**: 수 체계 변환은 동일한 수치 데이터를 표현하는 기수를 변경하여 서로 다른 진법(2진, 8진, 10진, 16진 등) 사이의 표기법을 일치시키는 산술적 절차임
- **배경/필요성**: 컴퓨터 하드웨어는 온/오프 상태의 2진수만을 인식하지만, 대규모 비트 데이터를 사람이 직관적으로 분석하고 디버깅하기 위해 2진수와 변환이 용이한 8진수나 16진수와 같은 압축된 표기법이 필요함

## Ⅱ. 특징

- 2진수와 8진수($2^3$), 16진수($2^4$) 사이의 변환은 비트를 3개 또는 4개씩 묶어 일대일로 대응시키는 것만으로 가능하여 계산 오버헤드가 거의 없음
- 10진수로의 변환 시에는 정수부는 기수로 반복 나눗셈을, 소수부는 반복 곱셈을 수행하는 '제분법/승분법'을 적용하며, 이 과정에서 무한 소수가 발생하여 오차가 생길 수 있음
- 16진수는 0~9 이후의 값(10~15)을 표현하기 위해 알파벳 A~F를 사용하여 한 자리에 더 많은 정보를 밀도 있게 담아낼 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 이진수 (Binary) | 8진수 (Octal) | 16진수 (Hexadecimal) |
|:---|:---|:---|:---|
| **기수 ($r$)** | 2 (0, 1) | 8 (0~7) | 16 (0~F) |
| **비트 밀도** | 1자리 = 1비트 | 1자리 = 3비트 | 1자리 = 4비트 |
| **주요 용도** | 회로 신호, 논리 연산 | 유닉스 파일 권한 (rwx) | 메모리 주소, 색상값 ($#RGB$) |
| **사람의 가독성** | 매우 낮음 (자릿수 과다) | 보통 | 매우 높음 (효율적 압축) |

> 요약: 하드웨어 기본값은 2진수이며, 이를 3비트씩 묶으면 8진수, 4비트씩 묶으면 16진수가 됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정수부 변환 | 원본 값을 목표 기수로 나누어 나머지를 역순으로 나열하는 '제분법'을 적용함 |
| 소수부 변환 | 원본 소수에 목표 기수를 곱해 발생하는 정수 부분을 순서대로 나열하는 '승분법'을 적용함 |
| 대응표 ($Lookup$) | 2진수 그룹($0000 \sim 1111$)과 16진수 기호($0 \sim F$) 사이의 고정된 매핑 관계임 |
| 자리값 가중치 | 각 진법의 위치별 가중치를 합산하여 10진수 크기로 환산하는 검증 기준임 |

```text
[ 2진수 -> 16진수 그룹핑 예시 ]
Binary: (1101)(0101)
Grouping: 1101 = D , 0101 = 5
Hex: D5
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 변환 진법 확인| --> | 정수/소수 분리| --> | 기수별 산술/매핑| --> | 결과 자릿수 검증|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **진법 식별** — 현재 수의 진법과 목표 진법을 확인하고, 10진수 개입 여부에 따라 계산 경로를 결정함
2. **부위 분리** — 소수점을 기준으로 정수 부분과 소수 부분을 나누어 각각의 변환 규칙을 독립적으로 준비함
3. **변환 실행** — (10진수 포함 시) 반복 나눗셈/곱셈을 수행하거나, (2/8/16진 사이) 비트를 3개 또는 4개씩 묶어 기호로 치환함
4. **결합 및 검증** — 변환된 정수부와 소수부를 결합하고, 역변환을 통해 원래의 수치값과 일치하는지 최종 확인함

## Ⅵ. 실무 적용 및 유의점

1. 메모리 주소나 레지스터 값을 16진수로 표기할 때, 데이터 버스 크기(예: 32비트)와 16진수 자릿수(예: 8자리)를 정확히 맞춰 표기해야 하며, 최상위 비트가 0인 경우라도 생략하지 말고 '0x' 접두사와 함께 명시하여 데이터 길이의 오해를 방지해야 함
2. 유닉스 시스템 권한($chmod$)을 8진수로 설정할 때, 한 자리가 사용자/그룹/기타의 rwx 권한(3비트)을 의미함을 인지하고, 755(111 101 101)와 같은 8진 표기가 실제 2진 비트 권한과 완벽히 대응되는지 확인하여 보안 설정 오류를 차단해야 함

## Ⅶ. 결론

- 수 체계 변환은 데이터의 물리적 저장 구조와 논리적 해석 구조를 연결하는 필수적인 기초 절차이며, 설계자는 진법 간의 비트 대응 관계와 산술적 변환 원리를 정확히 적용하여 데이터 처리의 정확성을 확보해야 함
