## Ⅰ. 개요

- **정의**: 수 체계 변환은 동일한 수량을 기수(Base/Radix)가 다른 진법 표기로 바꾸는 것임.
- **배경/필요성**: 컴퓨터는 전압의 고/저 2상태만 구분하므로 내부적으로 이진법(Base-2)을 쓰지만, 이진수는 자릿수가 길어 사람이 읽고 기록하기 어려움. $2^3=8$, $2^4=16$처럼 이진법과 정수배 관계인 8진·16진법으로 표기를 압축하는 변환이 필요해짐.
- **출제 의도**: 나눗셈 반복법·곱셈 반복법 절차의 정확한 적용력, 2진↔8진/16진이 비트 그룹핑만으로 즉시 상호 변환되는 원리 이해, 대상 데이터 성격에 맞는 진법 선택 판단력을 확인함.
- **답안 방향**: 구조(기수·자릿값·숫자기호·그룹핑 단위) -> 동작(나눗셈 반복법·그룹핑 계산 예시) -> 비교(8진·16진의 적용 조건) -> 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 10진→N진 변환 절차와 2진↔8진/16진 그룹핑 원리 설명 요구 | 나눗셈 반복법의 나머지 역순 규칙, 3비트/4비트 그룹핑 대응, 가중치 전개식 검산 | 나머지 읽는 순서 오류, 그룹핑 단위(3비트 vs 4비트) 혼동, 진법 선택 근거 없는 나열 |

> 요약: 이 답안은 나눗셈 반복법의 정확한 절차와 2진↔8진/16진 그룹핑의 성립 조건을 먼저 못 박고, 그 위에서 진법별 적용 기준을 논증해야 함.

## Ⅱ. 구조 및 구성요소

```text
값(10진) -> 기수(N) 선택 -> 숫자기호 집합 확인 -> 변환 방법 적용 -> N진 표기 결과
              |                                                        |
              +-> 자릿값(N^k)                                          +-> 가중치 합산으로 검산
```

| 구성요소 | 역할 | 예시/비유 |
|:---|:---|:---|
| 기수(Base/Radix, N) | 그 진법에서 사용 가능한 숫자 기호의 개수를 정함 | 2진=2개(0,1), 8진=8개(0-7), 16진=16개(0-9,A-F) |
| 자릿값(위치 가중치) | 각 자리가 나타내는 크기, $N^{(자리 위치)}$ | 10진에서 자릿값은 1, 10, 100, ... |
| 숫자기호 집합 | 자릿값에 채워 넣는 실제 기호 | 16진법은 10~15를 A~F로 표기 |
| 그룹핑 단위 | 2진수를 8진은 3비트, 16진은 4비트씩 묶어 1자리로 대응 | $2^3=8$, $2^4=16$이므로 정수배 그룹핑이 성립 |

> 요약: 기수가 자릿값과 숫자기호 집합의 범위를 정하고, 그룹핑 단위는 2진법과 8진/16진법 사이에서만 성립하는 변환 지름길임.

## Ⅲ. 동작원리 및 흐름도

```text
값 입력 -> 정수부/소수부 분리
정수부 -> N으로 반복 나눗셈, 나머지를 역순으로 기록 -> N진 정수부
소수부 -> N을 반복 곱셈, 정수부를 순서대로 기록 -> N진 소수부
2진 결과 -> 3비트/4비트 그룹핑 -> 8진/16진 결과 (나눗셈 없이 즉시 변환)
```

- 1단계(정수부 변환, 나눗셈 반복법): $156_{10}$을 2로 나눈 몫과 나머지를 몫이 0이 될 때까지 반복함. $156\div2=78\cdots0$, $78\div2=39\cdots0$, $39\div2=19\cdots1$, $19\div2=9\cdots1$, $9\div2=4\cdots1$, $4\div2=2\cdots0$, $2\div2=1\cdots0$, $1\div2=0\cdots1$. 나머지를 마지막에서 처음 순서로 읽으면 $156_{10}=10011100_2$.
- 2단계(비트 그룹핑, 2진→8진): $10011100_2$을 오른쪽부터 3비트씩 묶어 `010 011 100`으로 정렬하면(최상위에 0 보충) 각 그룹이 2, 3, 4이므로 $156_{10}=234_8$.
- 3단계(비트 그룹핑, 2진→16진): 같은 이진수를 오른쪽부터 4비트씩 묶으면 `1001 1100`이며 각 그룹이 9, C(=12)이므로 $156_{10}=9C_{16}$.
- 4단계(역변환 검증, 가중치 전개법): N진수를 10진으로 되돌릴 때는 각 자릿값에 $N^{(위치)}$를 곱해 더함. $9C_{16}=9\times16^1+12\times16^0=144+12=156$으로 원값과 일치함(검산 완료).

> 요약: 정수부는 나눗셈 반복 + 나머지 역순으로 변환하고, 2진↔8진/16진은 나눗셈 없이 그룹핑만으로 즉시 상호 변환되며, 가중치 전개법으로 결과를 검산함.

## Ⅳ. 특징

- 자릿수 압축률: 16진법은 4비트를 1자리로 압축해 이진수 대비 자릿수가 1/4로 줄어듦(예: $255_{10}=11111111_2=FF_{16}$). 8진법은 3비트 압축으로 1/3 수준임.
- 변환 즉시성: 2진↔8진/16진은 그룹핑만으로 성립하나, 8진↔16진 직접 변환은 그룹핑 단위(3비트 vs 4비트)가 어긋나 반드시 2진을 경유해야 함.
- 소수부 유한성: 소수부 곱셈 반복법은 목표 진법의 소인수로 나누어떨어지지 않으면 무한 순환소수가 됨(예: $0.1_{10}$의 2진 변환). 이 유한 비트 저장 한계는 025(부동소수점 IEEE 754)의 반올림 오차와 직결됨.
- 표기 모호성: 진법을 명시하는 접두사(`0x`, `0o`, `0b`)나 첨자 없이 숫자만 쓰면 값 해석이 진법에 따라 달라짐.

> 요약: 16진법의 압축률과 그룹핑 즉시성이 실무 채택의 이유이나, 8진↔16진 직접 변환 불가와 소수부 무한 순환은 반드시 유의해야 할 한계임.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 기준 | 8진법(Base-8) | 16진법(Base-16) | 선택 기준 |
|:---|:---|:---|:---|
| 그룹핑 단위 | 3비트 | 4비트 | 대상 비트 폭이 3의 배수 의미 단위면 8진, 4의 배수(바이트 단위)면 16진 |
| 대표 용도 | Unix 파일 권한(rwx 3비트) | 메모리 주소·색상 코드·해시값(바이트 단위) | 3비트 권한 단위처럼 의미가 고정되면 8진, 바이트 단위 데이터는 16진 |
| 자릿수 압축률 | 이진 대비 1/3 | 이진 대비 1/4 | 가독성·표기 길이가 최우선이면 16진이 더 짧음 |

> 요약: 대상 데이터의 의미 단위 비트 폭이 3비트(권한)냐 바이트 단위(4비트 배수)냐에 따라 8진과 16진 중 적합한 진법이 갈림.

**리스크·대응 (불릿):**
- 그룹핑 자릿수 오정렬: 이진수 길이가 3 또는 4의 배수가 아니면 그대로 묶었을 때 자릿값이 밀려 오변환됨 → 상위(왼쪽) 비트에 0을 보충해 배수를 맞춘 뒤 그룹핑함.
- 8진↔16진 직접 변환 시도: 그룹핑 단위가 서로 달라 직접 대응이 성립하지 않음 → 반드시 2진을 경유해 변환함.

**도입 후 점검 지표 (불릿):**
- 정확성: 가중치 전개법($N^{(위치)}$ 합산)으로 역변환해 원래 10진값과 일치하는지 검산함.
- 표기 명확성: 코드·문서에서 접두사(`0x`/`0o`/`0b`) 또는 첨자 표기로 진법을 명시했는지 확인함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 메모리 덤프·파일 권한 등 실무에서 다루는 데이터의 의미 단위 비트 폭(3비트/4비트 배수)을 식별해 8진·16진 표기 여부를 결정함.
2. 중기: 진법 변환·표기 규칙(접두사·대소문자)을 코드 컨벤션과 문서 표준으로 정착시킴.
3. 장기: IPv6·해시값 등 16진 표기가 확산되는 영역에서 RFC 5952 등 표준 표기 규칙을 조직 표준에 반영함.

- 기술사적 판단: 대상 데이터의 의미 단위 비트 폭(3비트 권한 vs 4비트/바이트)에 따라 8진과 16진 중 적합한 진법을 선택함.
- 기술사 제언: 그룹핑 변환은 나눗셈 없이 즉시 성립하는 지름길이나, 8진↔16진 직접 변환은 불가능하므로 항상 2진을 경유하도록 팀 컨벤션에 명시함.
