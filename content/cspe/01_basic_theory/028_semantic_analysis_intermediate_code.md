## Ⅰ. 개요
- **정의**: AST에 타입 검사·스코프 규칙을 적용하고, 기계 독립적 중간 표현(IR)을 생성하는 단계
- **배경/필요성**: 구문적으로 올바른 프로그램도 타입 불일치·미선언 변수 등 의미 오류를 포함할 수 있으므로 별도 검증이 필요함
- **비유**: 문법에 맞는 문장이라도 "물고기가 걸어간다"처럼 의미가 틀릴 수 있어 의미 검토가 필요한 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 구문 분석과 의미 분석의 역할 구분 | 속성 문법(Attribute Grammar)과 3-주소 코드 구조 | 의미 분석과 중간 코드 생성을 동일 단계로 혼동하지 않을 것 |

> 요약: AST의 의미 정합성을 검증한 뒤 기계 독립적 중간 코드를 생성하는 단계임

## Ⅱ. 구성요소
```text
  AST (from Parser)
       |
       v
  +-------------+     +-------------+     +-------------+
  | Type        |---->| Scope       |---->| IR Generator|
  | Checker     |     | Resolver    |     | (3-Addr)    |
  +-------------+     +-------------+     +-------------+
       |                                        |
       v                                        v
  Symbol Table                           Intermediate Code
  (타입 정보 갱신)                        (3-Address Code)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Type Checker | 연산자·피연산자 간 타입 호환성을 검증하고 묵시적 변환을 삽입함 | 단위가 다른 숫자의 연산 가능 여부를 확인하는 검수원 |
| Scope Resolver | 변수·함수의 선언 위치와 참조 범위를 심볼 테이블에서 확인함 | 같은 이름의 사람을 소속 부서로 구분하는 관리자 |
| IR Generator | AST를 3-주소 코드, SSA 등 기계 독립적 중간 표현으로 변환함 | 설계도를 시공사 무관한 표준 공정표로 변환하는 작업 |
| Symbol Table | 변수명·타입·스코프·오프셋 정보를 관리하는 중앙 자료구조 | 모든 부품의 규격이 기록된 부품 대장 |

> 요약: 타입 검사·스코프 해석 후 AST를 3-주소 코드 등 IR로 변환함

## Ⅲ. 절차
```text
  AST순회           타입검사          스코프해석        IR생성
  (DFS 탐색)       (타입 규칙)      (심볼 테이블)    (3-주소 코드)
       |              |              |              |
       +---속성전파--->+---검증------->+---변환------->+
    노드 방문       타입 일치 확인   선언/참조 매핑   중간 코드 출력
```
- 1단계: AST를 깊이 우선으로 순회하며 각 노드에 속성(Attribute)을 전파함
- 2단계: 연산식·대입문·함수 호출의 타입 호환성을 검사하고, 필요 시 타입 변환 노드를 삽입함
- 3단계: 심볼 테이블을 참조하여 변수·함수의 선언 범위와 참조 유효성을 확인함
- 4단계: 검증된 AST를 3-주소 코드(`t1 = a + b` 형태)로 변환하여 중간 표현을 출력함

> 요약: AST 순회 → 타입 검사 → 스코프 해석 → 3-주소 코드 생성 순서로 진행함

## Ⅳ. 문제점
- 타입 추론 복잡도: 다형성·제네릭이 포함된 언어에서 타입 추론 알고리즘의 시간 복잡도가 급증함
- 심볼 테이블 관리 부담: 중첩 스코프가 깊어질수록 심볼 검색 경로가 길어져 분석 속도가 저하됨
- IR 표현력 한계: 단일 IR 형식으로 다양한 목적 기계의 특성을 모두 반영하기 어려움

> 요약: 타입 추론 복잡도·심볼 관리 부담·IR 표현력 한계가 주요 문제임

## Ⅴ. 개선방안
1. 단기: Hindley-Milner 등 효율적 타입 추론 알고리즘을 적용하여 추론 복잡도를 제어함
2. 중기: 해시 기반 계층적 심볼 테이블을 도입하여 중첩 스코프 검색 시간을 O(1)에 근접시킴
3. 장기: 다단계 IR(High-IR → Mid-IR → Low-IR) 계층 구조를 도입하여 단계별 추상 수준을 조절함

> 요약: 효율적 추론·해시 심볼 테이블·다단계 IR로 의미 분석 품질을 향상함

## Ⅵ. 전망
- 발전 방향: MLIR(Multi-Level IR) 같은 다단계 중간 표현 프레임워크가 범용 컴파일러 인프라로 확산 중임
- 기술사적 판단: 의미 분석 정확도가 컴파일 타임 오류 검출률을 결정하므로 소프트웨어 품질에 직결됨
- 기술사 제언: 타입 시스템 이론과 IR 설계 원칙을 함께 이해해야 최적화·코드 생성 단계와의 연계가 가능함
