# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 나이브 베이즈는 **지도 학습**에 속하는 확률적 분류 알고리즘으로, **베이즈 정리(Bayes' Theorem)**를 기반으로 "모든 특징(조건)이 서로 독립적이다"라는 극단적이고 순진한(Naive) 가정을 적용해 사후 확률을 계산한다.
- **왜 필요한가**: 수만 개의 단어가 나오는 문서나 스팸 메일을 분류할 때, 단어 간의 복잡한 연관성을 다 계산하면 경우의 수가 폭발한다. 단어들이 서로 독립이라고 "퉁치면" 연산이 곱셈 몇 번으로 끝나 엄청나게 빨라진다.
- **핵심 직관**: 스팸 메일에 "당첨", "무료"라는 단어가 나왔다면, 원래는 두 단어가 같이 나올 복잡한 관계까지 따져야 하지만, 나이브 베이즈는 "스팸일 때 '당첨'이 나올 확률 × '무료'가 나올 확률"로 그냥 곱해버려 스팸 여부를 초고속으로 판정한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 지도 학습 (Supervised Learning) | 정답 라벨이 있는 데이터로 학습하는 상위 패러다임 — 나이브 베이즈가 속한 분류 | 정답지를 보며 배우는 학습 방식 |
| 베이즈 정리 (Bayes' Theorem) | 새로운 증거(데이터)가 주어졌을 때 사전 확률을 사후 확률로 갱신하는 통계 공식 | 첫인상(사전)을 근거(데이터)를 본 뒤 다시 판단(사후)하는 과정 |
| 사전 확률 (Prior, $P(C)$) | 데이터를 보기 전, 클래스 $C$ 자체가 발생할 확률 | 메일함에서 스팸이 원래 몇 % 섞여 있는지 |
| 우도/가능도 (Likelihood, $P(x_i \mid C)$) | 클래스 $C$일 때 특징 $x_i$가 나타날 조건부 확률 | 스팸 메일 중에서 "무료"라는 단어가 나올 비율 |
| 사후 확률 (Posterior, $P(C \mid X)$) | 데이터 $X$를 관찰한 뒤 클래스 $C$일 확률 — 최종 구하려는 값 | 단어들을 다 본 뒤 최종적으로 매기는 스팸 여부 판단 |
| 조건부 독립 가정 (Naive 가정) | 모든 특징이 클래스가 주어졌을 때 서로 영향을 주지 않는다고 가정 | "무료"와 "당첨"이 같이 나오는 경향을 무시하고 각각 따로 취급 |
| 라플라스 스무딩 (Laplace Smoothing) | 한 번도 못 본 단어 때문에 확률이 0이 되는 것을 막기 위해 모든 빈도에 +1을 더하는 보정 | 아무도 안 먹어본 메뉴에도 "최소 1명은 먹어봤다"고 가정해 평점 0 방지 |
| Zero Frequency 문제 | 훈련 데이터에 없던 단어의 우도가 0이 되어 곱셈 전체가 0이 되는 현상 | 곱셈에서 숫자 하나가 0이면 전체 답이 0이 되는 것과 같은 원리 |
| 언더플로우 (Underflow) | 1보다 작은 확률을 수천 번 곱하다 보면 부동소수점 표현 한계로 0이 되어버리는 현상 | 아주 작은 숫자를 계속 나누다 계산기가 결국 0으로 반올림하는 것 |

## 깊이 이해

### 실제 숫자로 사후 확률 계산해보기
- 훈련 메일 100통 중 스팸 40통, 정상 60통이 있다고 하자. 사전 확률은 $P(\text{스팸})=0.4$, $P(\text{정상})=0.6$이다.
- 스팸 40통 중 "무료"라는 단어가 포함된 메일이 30통이면 $P(\text{무료}\mid\text{스팸})=30/40=0.75$다. 정상 60통 중 "무료"가 포함된 메일이 6통이면 $P(\text{무료}\mid\text{정상})=6/60=0.1$이다.
- 새 메일에 "무료"가 등장했을 때, 베이즈 정리로 사후 확률에 비례하는 값을 계산한다(분모 $P(\text{무료})$는 두 클래스에 공통이라 비교 시 생략 가능).
  - 스팸 쪽: $P(\text{무료}\mid\text{스팸}) \times P(\text{스팸}) = 0.75 \times 0.4 = 0.30$
  - 정상 쪽: $P(\text{무료}\mid\text{정상}) \times P(\text{정상}) = 0.1 \times 0.6 = 0.06$
  - 두 값을 정규화하면 스팸일 확률 $= 0.30 / (0.30+0.06) = 0.833$, 즉 **약 83.3%**로 스팸 판정. 이렇게 여러 단어("무료", "당첨", "대출" 등)의 우도를 모두 곱해나가면서 최종 클래스를 정하는 것이 MAP(Maximum A Posteriori) 판정이다.

### 왜 "조건부 독립"을 가정해야 하나 — 차원의 저주 회피
- 원래는 "무료"와 "당첨"이 같은 메일에 함께 나올 결합 확률 $P(\text{무료}, \text{당첨} \mid \text{스팸})$을 구해야 하는데, 단어(특징)가 10개만 돼도 조합의 경우의 수가 기하급수로 늘어나 훈련 데이터로는 도저히 다 채울 수 없다(차원의 저주). 조건부 독립을 가정하면 이 결합 확률이 $P(\text{무료}\mid\text{스팸}) \times P(\text{당첨}\mid\text{스팸})$처럼 개별 확률의 곱으로 쪼개져, 단어마다 독립적으로 빈도만 세면 되므로 연산이 특징 수에 비례하는 선형 시간 $O(N \times F)$로 끝난다.

### Zero Frequency와 라플라스 스무딩을 숫자로
- 훈련 스팸 40통 중 "특가"라는 단어가 한 번도 나오지 않았다면 $P(\text{특가}\mid\text{스팸})=0/40=0$이다. 이 값이 곱셈에 들어가는 순간 다른 단어들의 확률이 아무리 높아도 전체 곱이 0이 되어버려 판정이 무너진다.
- 라플라스 스무딩은 분자에 +1, 분모에 전체 어휘 수 $V$를 더한다. 어휘 수가 $V=1000$이라면 $P(\text{특가}\mid\text{스팸}) = (0+1)/(40+1000) \approx 0.00096$로, 0이 아닌 아주 작은 값이 되어 곱셈이 죽지 않는다.

### 언더플로우와 로그 변환
- 문서 하나에 단어가 1,000개 있고 각 단어의 우도가 평균 0.01 수준이라면, 이를 1,000번 곱한 값($0.01^{1000}$)은 컴퓨터의 부동소수점이 표현할 수 있는 최소값보다 작아져 그냥 0으로 처리되어 버린다(Underflow). 그래서 실무에서는 확률을 직접 곱하지 않고, 로그를 취해 곱셈을 덧셈으로 바꾼다: $\log P(C\mid X) \propto \log P(C) + \sum \log P(x_i\mid C)$. 덧셈은 값이 작아져도 0으로 소멸하지 않으므로 안전하다.

### 비유와 흔한 오해
- 비유: 한 사람의 성별을 맞출 때 "머리가 길 확률"과 "립스틱을 바를 확률"은 사실 깊은 연관이 있다. 하지만 나이브 베이즈는 순진하게 "두 사건은 전혀 무관하다"고 무시한 채 확률만 곱해서 빠르게 판정한다. 놀랍게도 실전에서는 이 단순화가 꽤 잘 맞는다 — 클래스를 가르는 결정 경계 자체는 독립 가정이 다소 어긋나도 크게 흔들리지 않기 때문이다.
- 오해: 독립 가정이 깨져도 "분류(어느 클래스인지)" 자체는 비교적 잘 맞는 경우가 많지만, 나이브 베이즈가 뱉는 "확률값"(예: 스팸일 확률 83.3%)의 정밀도는 왜곡되기 쉽다. 확률값 자체를 신뢰도 지표로 그대로 쓰면 안 되고, 어느 클래스가 더 그럴듯한지 순위를 매기는 용도로 주로 쓴다.

## 연결 개념
- 베이즈 정리 (Bayes' Theorem) — 사전 확률을 이용해 사후 확률을 업데이트하는 통계학의 핵심 원리
- 라플라스 스무딩 (Laplace Smoothing) — 0을 곱해서 모든 확률이 소멸하는 것을 막는 보정 기법
- 결정 트리, SVM — 나이브 베이즈와 함께 전통적 머신러닝 분류기의 대표 주자 (059, 061 참고)

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 나이브 베이즈 분류기는 베이즈 정리(Bayes' Theorem)를 기반으로, 모든 입력 변수(Feature)가 상호 조건부 독립(Conditionally Independent)이라는 강한 가정을 적용한 확률적 분류 알고리즘이다.
> 2. **가치**: 피처 수 증가에 따른 결합 확률 연산량의 지수적 폭발을 단순 곱셈 연산 $O(N \times F)$으로 압축하여, 희소(Sparse)한 고차원 텍스트 데이터 환경에서 실시간 훈련/추론을 가능하게 한다.
> 3. **판단 포인트**: '독립 가정'이라는 논리적 결함에도 불구하고 분류 경계선 도출에는 매우 강력하나, 반환되는 확률값 자체의 신뢰도는 떨어지므로 확률 정밀도가 필요한 예측에는 부적합하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 수학적 가정(Naive)의 원리 이해 | 독립 가정을 통한 결합 확률 $\rightarrow$ 한계 확률의 연속 곱셈 변환 수식 | '순진하다'고만 쓰고 왜 연산량이 줄어드는지 수식 설명 누락 |
| 실무 제약(Zero Frequency) 해결 역량 | 빈도수 0일 때의 곱셈 소멸 방지를 위한 라플라스(Laplace) 스무딩 | 언코딩된 범주형 데이터 처리의 약점 미기재 |
| 고차원 희소 데이터 처리 알고리즘 선택 | 스팸 필터링, 문서 분류에서의 강점과 타 모델(SVM, DT)과의 비교 | 비선형적 복잡성을 가진 데이터에 강하다고 단정 |

> 요약: 차원의 저주를 피하기 위해 통계적 엄밀함(상관관계)을 과감히 버리고, 연산 속도와 고차원 처리 능력을 획득한 기회비용(Trade-off)을 수식으로 묻는다.

## Ⅰ. 개요 및 필요성

- 정의: 데이터의 모든 특징(Feature)이 클래스 라벨이 주어졌을 때 상호 독립적이라는 가정 하에 베이즈 정리를 적용하는 확률 모델
- 배경: 피처 10만 개의 텍스트 문서 분류 시, 피처 간의 연관성(Covariance)을 계산하는 것은 연산 자원과 데이터 부족으로 불가능(차원의 저주)
- 필요성: 매우 큰 차원과 극소수의 훈련 샘플만으로도 모델 훈련이 수렴하고, 실시간(Millisecond) 판정이 가능한 경량 분류기 요구

## Ⅱ. 구조 및 구성요소 (수학적 전개)

```text
[베이즈 정리 기본] P(C | X) = { P(X | C) * P(C) } / P(X)
  | 
  | '조건부 독립(Naive)' 가정 적용 시 P(X | C)가 분리됨
  v
[나이브 베이즈]   P(C | x_1, x_2, ..., x_n) ∝ P(C) * Π [ P(x_i | C) ]
```

| 구성요소 | 역할 | 수식 / 특이사항 |
|:---|:---|:---|
| 사후 확률 (Posterior) | 특정 피처 집합 $X$가 주어졌을 때 클래스 $C$일 확률 | $P(C \mid X)$ (최종 구하고자 하는 값) |
| 사전 확률 (Prior) | 데이터 $X$와 무관하게 클래스 $C$ 자체가 발생할 확률 | $P(C)$ (훈련 데이터의 라벨 비율) |
| 우도 / 가능도 (Likelihood) | 클래스 $C$일 때 피처 $x_i$가 나타날 조건부 확률 | $P(x_i \mid C)$ (조건부 독립 가정에 의해 개별 곱셈) |
| 라플라스 스무딩 (Smoothing) | 빈도수 0으로 인한 곱셈 소멸 방지 상수($\alpha$) 추가 | $\frac{N(x_i, C) + \alpha}{N(C) + \alpha \cdot V}$ |

> 요약: "A, B, C가 동시에 일어날 확률"을 구하는 대신, 독립 가정을 핑계로 "A확률 × B확률 × C확률"로 쪼개어 계산 복잡도를 혁신적으로 낮춘다.

## Ⅲ. 세부 알고리즘 종류 및 동작

```text
텍스트 벡터화(BoW, TF-IDF) -> Prior 확률 및 Likelihood 확률 테이블 계산 -> Smoothing 적용 -> 최대 확률 클래스 출력(MAP)
```

| 구분 (종류) | 특징(Feature) 데이터 형태 | 최적 적용 도메인 |
|:---|:---|:---|
| 가우시안 (Gaussian NB) | 연속적인 실수(Continuous) 수치 데이터 | 피처가 정규 분포를 따른다고 가정 (키, 몸무게 측정 데이터) |
| 다항 분포 (Multinomial NB) | 발생 횟수, 빈도(Frequency) 등 이산형 카운트 | 텍스트 문서 분류, 단어 빈도 기반(BoW) 스팸 필터링 |
| 베르누이 (Bernoulli NB) | 0과 1의 이진(Binary) 데이터 | 특정 단어의 문서 내 출현 여부(O/X)만 판단하는 분류 |

> 요약: 나이브 베이즈는 데이터가 소수점이냐(Gaussian), 몇 번 나왔냐(Multinomial), 있냐 없냐(Bernoulli)에 따라 3가지 함수식을 골라 써야 한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 피처 수·데이터량과 무관하게 $O(N \times F)$ 선형 시간 학습, 소량 표본으로도 확률 추정 수렴 | 콜드스타트·실시간 재학습 환경에 적합 |
| 한계 | 조건부 독립 가정 위반 시 분류 경계는 유지되어도 사후 확률(Posterior) 값 자체가 과신 또는 과소신으로 왜곡 | 확률값을 신뢰도 지표로 그대로 쓰면 오판, 별도 캘리브레이션 필요 |
| 데이터 편향 취약성 | 학습 데이터의 클래스 비율이 사전 확률(Prior)에 그대로 반영되어 소수 클래스가 묻힘 | 불균형(Imbalanced) 데이터 시 사전 확률 보정 또는 리샘플링 필요 |

> 요약: 나이브 베이즈는 속도와 소량 데이터 수렴성이 강점이나, 독립 가정 위반에 따른 확률 신뢰도 저하와 클래스 불균형에 따른 사전 확률 왜곡이라는 구조적 한계를 함께 지닌다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 나이브 베이즈 (Naive Bayes) | 로지스틱 회귀 (Logistic Regression) | 선택 기준 |
|:---|:---|:---|:---|
| 모델 유형 | 생성 모델(Generative) - 데이터 분포 $P(X,Y)$ 모형화 | 판별 모델(Discriminative) - 경계 $P(Y \mid X)$ 학습 | 데이터량 한계시 NB가 유리 |
| 피처 독립성 | 상호 완전 독립으로 강제 규정 (상관관계 무시) | 피처 간의 다중공선성/상관관계 일부 반영 | 피처 간 의존성 강할 시 로지스틱 |
| 학습 속도 | 극단적으로 빠름 (단 1회의 확률 카운트 횡단) | 최적화(Gradient Descent) 반복 연산으로 상대적 느림 | 훈련 제약 시간 (실시간 갱신) |

> 요약: 로지스틱 회귀가 천천히 정답 경계선을 다듬어간다면, 나이브 베이즈는 데이터를 한 번 훑으며 통계(확률 빈도)를 내고 즉시 훈련을 끝내는 '생성 모델'이다.

| 리스크 | 발생 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Zero Frequency 현상 | 테스트 데이터에 훈련 시 한 번도 없던 단어/피처 출현 | 라플라스/애드원(Add-One) 스무딩 적용 (모든 빈도에 +1) | 확률 연산 결과의 0 수렴 여부 |
| Underflow (정밀도 손실) | 1 이하 확률 1만 개를 연속 곱셈 시 부동소수점 한계로 0 처리 | 곱셈($\Pi$)을 $\log$ 합($\Sigma$) 연산으로 치환하여 계산 | $\log$ 우도(Log-Likelihood) 확인 |

> 요약: 나이브 베이즈의 실무 리스크는 모델 성능이 아니라 확률 연산의 수치적 소멸(0 또는 Underflow)이며, 스무딩과 로그 변환으로 사전에 통제해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 실시간 스팸 필터 및 악플 차단기: 일 1,000만 건 이상 쏟아지는 이메일/댓글 텍스트를 Multinomial NB로 매핑하여, 복잡한 딥러닝 인퍼런스 서버 없이 웹 서버 메모리 내에서 1ms 이내로 1차 필터링 수행.
2. 콜드스타트(Cold-Start) 추천/분류 시스템 구축: 초기 서비스 론칭으로 레이블링된 데이터가 수백 건에 불과할 때, 강력한 수학적 가정을 가진 나이브 베이즈를 적용하여 과적합 없이 초기 분류기(Baseline) 배포.
3. 앙상블 체계의 희소 데이터 처리 모듈: 고객 행동 이력 등 10만 차원의 희소(Sparse) 행렬 데이터가 트리 모델(Random Forest)을 느리게 만들 때, 이를 NB가 받아 확률값 기반의 저차원 메타 피처 1개로 압축하여 전달(Stacking 전처리).

**결론 (2줄):**
- 기술사 판단: 나이브 베이즈 분류기는 "특징 간 완전 독립"이라는 현실과 동떨어진(Naive) 가정을 취했으나, 오히려 이 결함 덕분에 희소 고차원 데이터에서 차원의 저주를 회피하는 가장 빠르고 안정적인 모델이다.
- 향후 방향: 딥러닝(Transformer)이 주도하는 현대 NLP에서는 메인 모델 지위를 상실했으나, 초거대 데이터 1차 필터링이나 실시간 엣지 디바이스 분류 같은 '속도 지상주의' 영역에서는 여전히 필수 베이스라인이다.
