# 020. 오토마타 이론 — DFA·NFA (Automata Theory)

## 미리 알고가기

- **유한 오토마타 (Finite Automata)**: 유한한 수의 상태와 입력 기호에 따른 상태 전이로 동작하는 추상적 계산 기계임
- **정규 언어 (Regular Language)**: 유한 오토마타가 인식할 수 있는 언어의 집합이며, 정규 표현식(Regex)과 등가임
- **전이 함수 (Transition Function)**: 현재 상태와 입력 기호를 매핑하여 다음 상태를 결정하는 규칙임

## 1. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열에 따라 내부 상태를 변화시키며 해당 문자열이 정해진 규칙(언어)을 만족하는지 판별하는 수학적 모델이며, 전이의 결정성 여부에 따라 DFA와 NFA로 분류됨
- **배경/필요성**: 텍스트 패턴 매칭, 컴파일러의 어휘 분석(Lexical Analysis), 통신 프로토콜 상태 검증 등에서 정교한 제어 로직을 하드웨어나 소프트웨어로 구현하기 위한 이론적 토대를 제공함

## 2. 특징 및 비교

결정적 유한 오토마타(DFA)와 비결정적 유한 오토마타(NFA)는 표현 가능한 언어의 범위(정규 언어)가 동일하나, 구현 효율성과 직관성 면에서 차이가 있음.

| 비교 항목 | DFA (Deterministic) | NFA (Non-deterministic) |
|:---|:---|:---|
| **전이의 유일성** | **상태와 입력당 다음 상태가 오직 하나** | 하나의 입력으로 여러 상태 전이 가능 |
| **공백(ε) 전이** | 허용되지 않음 | **입력 없이 상태 전이 가능 (ε-move)** |
| **구현 난이도** | 쉬움 (단순 테이블 참조) | 어려움 (백트래킹 또는 병렬 탐색) |
| **표현 직관성** | 장황하고 복잡해질 수 있음 | **간결하고 설계가 용이함** |
| **수행 속도** | 매우 빠름 ($O(n)$) | 상대적으로 느림 (상태 집합 추적 필요) |
| **상태 수** | NFA를 변환 시 최대 $2^n$개로 폭증 | 상대적으로 적은 상태로 유지 가능 |

> 요약: 인간은 NFA로 패턴을 설계하는 것이 편하며, 컴퓨터는 이를 DFA로 변환하여 실행하는 것이 효율적임.

## 3. 구성요소/구조

유한 오토마타는 5-튜플($M = (Q, \Sigma, \delta, q_0, F)$)로 수학적으로 정의됨.

- **구성요소**:
  - $Q$: 유한한 상태들의 집합
  - $\Sigma$: 입력 기호들의 집합 (Alphabet)
  - $\delta$: 전이 함수 ($Q \times \Sigma \rightarrow Q$ 또는 $Q \times \Sigma \rightarrow P(Q)$)
  - $q_0$: 시작 상태 ($q_0 \in Q$)
  - $F$: 수용 상태(Accepting States)의 집합 ($F \subseteq Q$)

- **동작 원리 (ASCII 흐름도)**:

```text
[Input String] -> [State Transition] -> [Final Acceptance]
      |                   |                     |
   "a b b a"      q0 --a--> q1 --b--> q2      q_final IN F ?
```

1. **상태 전이**: 입력 문자열을 한 글자씩 읽을 때마다 전이 함수 $\delta$에 의해 현재 상태가 갱신됨
2. **비결정성 해소**: NFA의 경우 가능한 모든 경로 중 하나라도 수용 상태에 도달하면 해당 문자열을 수용함
3. **수용 판정**: 모든 입력을 소진한 시점의 최종 상태가 $F$에 속하면 'Accept', 그렇지 않으면 'Reject'함

## 4. 문제점 및 개선방안

1. **DFA 상태 폭발 (State Explosion)**: 복잡한 NFA나 정규식을 DFA로 변환할 때 상태 수가 지수적으로 증가하여 메모리 부족을 유발함
   - **개선방안**: 부분집합 구성법(Subset Construction) 수행 시 도달 가능한 상태만 생성하고, **DFA 최소화 알고리즘(Minimization)**을 통해 중복되거나 등가인 상태를 통합함 (확인: 최소 상태 수 도달 여부)

2. **메모리 없는 계산의 한계**: 유한 오토마타는 현재 상태 외에 과거를 기억하는 저장소가 없어, 괄호 쌍 맞추기($a^n b^n$)와 같은 문맥 자유 언어를 처리하지 못함
   - **개선방안**: 스택(Stack) 메모리를 추가한 **푸시다운 오토마타 (PDA)**로 확장하거나, 정규 언어 범위를 벗어나는 패턴은 파서(Parser)를 사용함 (확인: 언어의 계층 구조 분석)

3. **ReDoS (Regular Expression DoS)**: NFA 기반 엔진에서 복잡한 패턴 매칭 시 백트래킹이 과도하게 발생하여 CPU 자원을 고갈시킴
   - **개선방안**: 매칭 엔진을 NFA 시뮬레이션 방식에서 DFA 기반으로 교체하거나, 정규식 설계 시 중첩된 반복문(Ambiguous Patterns)을 지양함 (확인: 최악의 입력 시 매칭 시간)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 컴파일러 어휘 분석기 | 소스코드를 읽어 키워드, 식별자, 상수를 추출하기 위한 Lexer 구현에 사용 | 토큰 추출 속도, 예약어 식별 정확도 |
| 프로토콜 상태 제어 | TCP 3-way handshake나 결제 게이트웨이의 상태 전이도를 설계하고 검증 | 유효하지 않은 상태 전이 차단율 |
| 텍스트 검색 엔진 | 정규 표현식을 오토마타로 변환하여 대용량 텍스트 내 패턴 고속 검색 (grep 등) | 초당 처리 바이트 (Throughput) |
| 하드웨어 제어 유닛 | 입력 신호 조합에 따라 기계를 제어하는 순서 논리 회로(FSM) 설계 | 회로 게이트 수, 동작 지연(Latency) |

> 요약: 문자열 판별부터 복잡한 시스템의 상태 관리까지 현대 컴퓨팅의 로직 설계를 지탱하는 기초 모델임.

## 6. 결론

오토마타 이론은 계산 가능한 것이 무엇인지를 정의하는 컴퓨터 과학의 근간임. 기술사는 단순히 정규식을 사용하는 수준을 넘어, 이를 실행하는 하부 엔진이 DFA인지 NFA인지에 따른 성능 특성을 파악하고, 상태 폭발이나 ReDoS와 같은 실무적 위험을 제어할 수 있어야 함.

또한 유한 오토마타의 한계를 명확히 인식하여, 더 복잡한 언어 처리가 필요할 때는 푸시다운 오토마타나 튜링 머신과 같은 상위 모델을 선택할 수 있는 판단력이 요구됨. 결국 오토마타는 복잡한 제어 로직을 '유한한 상태'로 추상화하여 예측 가능하고 안전한 시스템을 구축하기 위한 필수적인 설계 도구임.
