## 미리 알고가기

- 상태(State): 입력 처리 중 시스템이 가질 수 있는 유한한 제어 위치임
- 입력 알파벳: 오토마타가 읽을 수 있는 기호의 집합임
- 전이 함수: 현재 상태와 입력 기호로 다음 상태를 정하는 규칙임
- 결정적 유한 오토마타(DFA): 같은 상태와 입력에 대해 다음 상태가 하나로 정해지는 유한 오토마타임
- 비결정적 유한 오토마타(NFA): 같은 상태와 입력에서 여러 상태 전이와 $\epsilon$-전이를 허용하는 유한 오토마타임
- $\epsilon$-폐쇄: 입력을 소비하지 않고 $\epsilon$-전이만으로 도달할 수 있는 상태 집합임
- 정규 언어: 유한 오토마타가 인식하는 문자열 집합임
- 시작·수용 상태: $q_0$은 입력 처리 전 상태, $F$는 입력 종료 후 수용 여부를 판정하는 상태 집합임
- 오토마타 표기: $Q$는 상태 집합, $\Sigma$는 입력 알파벳, $\delta$는 전이 함수임

## 작성 근거(검토용)

- **개요 구성**: 입력 소비, 상태 전이, 수용 판정이 오토마타의 핵심 절차라 정의에 모두 반영함
- **Ⅱ. 특징 선정**: 유한 상태, DFA 단순성, NFA 표현성, NFA-DFA 변환은 DFA·NFA 답안의 중심 판단임
- **Ⅲ 비교축 선정**: 전이 방식, 실행 상태, 동등 언어의 상태 수가 DFA와 NFA의 구현 차이를 가름
- **Ⅳ 구조 선정**: 5-튜플은 오토마타 설명의 표준 구성이라 기호와 역할을 표로 정리함
- 정규 표현식과 프로토콜 입력 검증은 NFA의 규칙 표현과 DFA의 단일 상태 실행을 보여주는 대표 사례임

## Ⅰ. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열을 순차적으로 읽고 도달 상태 집합과 수용 상태 집합의 교집합으로 언어 포함 여부를 판정하는 계산 모델임
- **배경/필요성**: 입력 흐름의 규칙 준수를 형식적으로 판단하기 위해 상태 전이 모델이 필요함

## Ⅱ. 특징

- 유한한 상태만 사용해 정규 언어의 수용 여부를 판정함
- DFA는 입력마다 전이 하나를 조회해 현재 상태 하나만 갱신함
- NFA는 한 입력의 여러 전이를 허용해 규칙을 표현하고 실행 시 상태 집합을 추적함
- 모든 NFA는 같은 언어를 인식하는 DFA로 변환됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 결정적 유한 오토마타 (DFA) | 비결정적 유한 오토마타 (NFA) |
|:---|:---|:---|
| 전이 방식 | 입력마다 하나의 다음 상태 | 입력 또는 $\epsilon$에 따른 다음 상태 집합 |
| 실행 상태 | 단일 상태 추적 | $\epsilon$-폐쇄 상태 집합 추적 |
| 동등 언어의 상태 수 | NFA $n$개 상태 변환 시 최대 $2^n$개 | 동등한 DFA보다 적은 상태로 표현 가능 |

> 요약: NFA는 여러 전이 후보로 규칙을 표현하고, DFA는 입력마다 하나의 현재 상태만 추적함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 기호 | 설명 |
|:---|:---|:---|
| 상태 집합 | $Q$ | 유한한 제어 상태 집합 |
| 입력 알파벳 | $\Sigma$ | 입력 문자열의 기호 집합 |
| 전이 함수 | $\delta$ | 현재 상태와 입력의 다음 상태 대응 |
| 시작 상태 | $q_0$ | 입력 처리 전의 초기 상태 |
| 수용 상태 집합 | $F$ | 문자열 수용을 판정하는 종료 상태 집합 |

```text
[ 오토마타 구조 ]
M = (Q, Sigma, delta, q0, F)
입력 기호 -> 현재 상태 -> 전이 함수 -> 다음 상태
도달 상태 중 F 포함 상태 존재 -> 수용
```

> 요약: 오토마타는 시작 상태에서 입력마다 전이하고 도달 상태 집합과 수용 상태 집합의 교집합으로 문자열을 판정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 상태 초기화 | --> | 입력 소비   | --> | 상태 전이   | --> | 수용 판정   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **상태 초기화**: DFA는 $q_0$, NFA는 $q_0$의 $\epsilon$-폐쇄를 현재 상태로 둠
2. **입력 소비**: 기호를 왼쪽부터 하나씩 읽음
3. **상태 전이**: 입력 전이 결과를 구하고 NFA는 결과의 $\epsilon$-폐쇄를 다음 상태 집합으로 둠
4. **수용 판정**: 입력 종료 후 도달 상태 집합과 $F$의 교집합이 있으면 수용함

> 요약: 오토마타는 입력을 모두 소비한 뒤 도달 상태 중 수용 상태가 있으면 문자열을 수용함.

## Ⅵ. 실무 사례

1. 정규 표현식 엔진은 패턴을 NFA로 구성하고 매칭 시간·상태 수를 확인함
2. 프로토콜 입력 검증기는 DFA 전이표로 구현하고 미정의 전이·수용 상태 판정을 확인함

## Ⅶ. 결론

- 오토마타는 NFA의 규칙 표현과 DFA의 단일 상태 실행을 구분하고 상태 수·전이 비용으로 구현 방식을 선택해야 함
