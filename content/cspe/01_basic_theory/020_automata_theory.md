## 미리 알고가기

- 상태(State): 지금까지 읽은 입력의 정보를 유한하게 요약한 제어 상태임
- 입력 알파벳: 오토마타가 읽을 수 있는 기호의 집합임
- 전이 함수: 현재 상태와 입력 기호로 다음 상태를 정하는 규칙임
- 결정적 유한 오토마타(DFA): 같은 상태와 입력에 대해 다음 상태가 하나로 정해지는 유한 오토마타임
- 비결정적 유한 오토마타(NFA): 같은 상태와 입력에서 여러 다음 상태를 허용하며 $\epsilon$-전이도 표현할 수 있는 유한 오토마타임
- $\epsilon$-폐쇄: 입력을 소비하지 않고 $\epsilon$-전이만으로 도달할 수 있는 상태 집합임
- 정규 언어: 유한 오토마타가 인식하는 문자열 집합임
- 시작 상태: $q_0$은 입력을 읽기 전의 초기 상태임
- 수용 상태 집합: $F$는 입력 종료 후 문자열의 수용 여부를 판정하는 상태 집합임
- 오토마타 표기: $Q$는 상태 집합, $\Sigma$는 입력 알파벳, $\delta$는 전이 함수임

## 작성 근거(검토용)

- **개요 구성**: 입력 소비, 상태 전이, 수용 판정이 오토마타의 핵심 절차라 정의에 모두 반영함
- **Ⅱ. 특징 선정**: 유한 상태, DFA 단순성, NFA 표현성, NFA-DFA 변환은 DFA·NFA 답안의 중심 판단임
- **Ⅲ. 비교축 선정**: 전이 방식, 실행 상태, 동등 언어의 상태 수는 DFA와 NFA의 구현 차이를 가름
- **Ⅳ. 구조 선정**: 5-튜플은 유한 오토마타의 표준 구성이므로 기호와 역할을 표로 정리함
- 정규 표현식과 프로토콜 입력 검증은 NFA의 규칙 표현과 DFA의 단일 상태 실행을 보여주는 대표 사례임

## Ⅰ. 개요

- **정의/개념**: 유한 오토마타는 입력 문자열을 순서대로 읽어 상태를 전이하고 수용 상태 도달 여부로 문자열을 판정하는 계산 모델임
- **배경/필요성**: 입력 흐름의 규칙 준수를 형식적으로 판단하기 위해 상태 전이 모델이 필요함

## Ⅱ. 특징

- 유한한 상태만 사용해 정규 언어의 수용 여부를 판정함
- DFA는 입력마다 전이 하나를 조회해 현재 상태 하나만 갱신함
- NFA는 한 입력의 여러 전이를 허용해 규칙을 표현하고 실행 시 상태 집합을 추적함
- 모든 NFA는 같은 언어를 인식하는 DFA로 변환됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 결정적 유한 오토마타 (DFA) | 비결정적 유한 오토마타 (NFA) |
|:---|:---|:---|
| 전이 방식 | 입력마다 하나의 다음 상태 | 입력 또는 $\epsilon$에 따른 다음 상태 집합 |
| 실행 상태 | 단일 상태 추적 | $\epsilon$-폐쇄 상태 집합 추적 |
| 동등 언어의 상태 수 | NFA $n$개 상태 변환 시 최대 $2^n$개 | 동등한 DFA 이하의 상태 수로 표현 |

> 요약: NFA는 여러 전이 후보로 규칙을 표현하고 DFA는 입력마다 하나의 현재 상태만 추적함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 상태 집합($Q$) | 유한한 제어 상태 집합 |
| 입력 알파벳($\Sigma$) | 입력 문자열을 구성하는 기호 집합 |
| 전이 함수($\delta$) | 현재 상태와 입력 기호를 다음 상태 또는 상태 집합에 대응시키는 함수 |
| 시작 상태($q_0$) | 입력 처리 전 오토마타가 위치하는 초기 상태 |
| 수용 상태 집합($F$) | 입력 처리가 끝났을 때 문자열의 수용을 나타내는 상태 집합 |

```text
[ 오토마타 구조 ]
M = (Q, Σ, δ, q0, F)
입력 기호 -> 현재 상태 -> 전이 함수 -> 다음 상태
도달 상태 집합 ∩ F ≠ ∅ -> 수용
```

> 요약: 유한 오토마타는 시작 상태에서 입력 기호마다 전이하고 입력 종료 후 수용 상태 도달 여부를 판정함.

## Ⅴ. 원리 및 절차 흐름도

```text
시작 상태 설정 → 입력 기호 소비 → 전이 함수 적용
                                  ├─ 입력 남음 → 다음 기호 반복
                                  └─ 입력 종료 → 수용 상태 포함 여부 판정
```

1. **상태 초기화**: DFA는 $q_0$을 현재 상태로, NFA는 $q_0$의 $\epsilon$-폐쇄를 현재 상태 집합으로 둠
2. **입력 소비**: 기호를 왼쪽부터 하나씩 읽음
3. **상태 전이**: 현재 상태에 입력 전이를 적용하고 NFA는 결과의 $\epsilon$-폐쇄를 다음 상태 집합으로 둠
4. **수용 판정**: 입력 종료 후 도달 상태 집합과 $F$의 교집합이 있으면 수용함

> 요약: 유한 오토마타는 입력을 모두 소비한 뒤 도달 상태 중 수용 상태가 있으면 문자열을 수용함.

## Ⅵ. 실무 사례

1. NFA 기반 정규 표현식 엔진은 패턴을 상태와 전이로 구성하고 매칭 시간과 상태 수가 처리 성능을 좌우함
2. 프로토콜 입력 검증기는 DFA 전이표로 구현하고 거부 상태 전이와 수용 상태 판정이 입력 규격 준수 여부를 가름

## Ⅶ. 결론

- 유한 오토마타는 유한한 상태 전이로 문자열을 판정하며, 규칙 표현은 NFA, 빠른 실행은 DFA가 적합함
- 외부 입력 검증에는 상태 수와 실행 상한을 두고, 중첩 구조가 들어오면 정규식 확장 대신 파서로 경계를 분리해야 함
