## 미리 알고가기

- 상태: 신호등이 지금 어떤 색인지처럼, 입력을 처리하는 중 시스템이 기억하는 현재 조건임
- 전이 함수: 특정 색에서 정해진 신호가 오면 다음 색으로 바뀌는 규칙처럼, 현재 상태와 입력에 따라 다음 상태를 정하는 규칙임
- 정규 언어: 유한 오토마타가 상태와 전이만으로 판정할 수 있는 문자열 집합이며, 괄호 개수처럼 이전 입력을 세어야 하는 패턴은 포함하지 않음
- $\epsilon$ 전이: 줄을 서다가 아무것도 내지 않고 바로 다음 창구로 넘어가는 것처럼, 입력 문자를 소비하지 않고 상태만 이동하는 전이임

## Ⅰ. 개요

- **정의/개념**: 오토마타는 입력 기호를 한 글자씩 읽으면서 현재 상태를 바꾸고, 입력을 모두 처리한 뒤 수용 상태 도달 여부로 문자열이 규칙을 만족하는지 판정하는 계산 모델임. 유한 오토마타의 대표 형태로는 하나의 입력에 대해 다음 상태가 하나로 정해지는 DFA(Deterministic Finite Automaton)와, 여러 다음 상태를 동시에 허용하는 NFA(Nondeterministic Finite Automaton)가 있음
- **배경/필요성**: 문자열 패턴 검사, 어휘 분석, 프로토콜 상태 검증처럼 입력 흐름을 규칙대로 통제해야 하는 영역에서는 규칙을 상태와 전이로 쪼개 어떤 입력을 빠뜨렸는지 빠짐없이 점검할 기준이 필요함

## Ⅱ. 특징

- 오토마타는 입력 처리 규칙을 상태와 전이로 고정하므로, 규칙 누락이나 정의되지 않은 입력을 표나 그래프만 보고도 바로 찾아낼 수 있음
- 오토마타는 상태 수가 유한하므로 어떤 입력이든 정해진 단계 안에서 수용 여부가 끝나며, 판정이 끝나지 않고 계속 진행되는 상황이 생기지 않음
- 오토마타가 다루는 언어 범위는 정규 언어로 한정되므로, 괄호 중첩처럼 이전 입력의 개수를 계속 기억해야 하는 패턴은 상태 수만으로 표현하지 못해 별도 모델이 필요함
- 오토마타는 상태 전이 규칙을 코드보다 먼저 다이어그램이나 표로 설계할 수 있어, 구현에 들어가기 전에 규칙 자체의 누락과 충돌을 따로 검증할 수 있음

## Ⅲ. 종류 및 비교

- **DFA(Deterministic Finite Automaton)**: 현재 상태와 입력 기호 하나가 정해지면 다음 상태가 항상 하나로 결정되는 유한 오토마타임. 자판기가 버튼 하나에 정확히 한 가지 동작만 내놓는 것처럼, 같은 상태에서 같은 입력이 들어오면 갈 곳이 하나뿐이라 구현과 실행 경로가 단순함
- **NFA(Nondeterministic Finite Automaton)**: 같은 상태와 같은 입력 기호에서도 여러 다음 상태를 동시에 허용하거나, 입력을 소비하지 않고 이동하는 $\epsilon$ 전이를 둘 수 있는 유한 오토마타임. 여러 갈래 길을 한꺼번에 열어두고 나중에 목적지에 닿았는지만 확인하는 방식이라 복잡한 패턴을 더 자연스럽게 표현함

| 판단 기준 | DFA | NFA |
|:---|:---|:---|
| 실행 시 추적해야 할 상태 | 현재 상태 하나만 유지하면 되어 실행 로직이 단순함 | 가능한 상태 후보 집합을 동시에 유지해야 해 실행 로직이 더 복잡함 |
| 빈 입력으로 이동하는 $\epsilon$ 전이 | 두지 않아 모든 이동이 실제 입력 소비와 연결됨 | $\epsilon$ 전이를 둘 수 있어 규칙을 더 간결하게 표현함 |
| 주로 쓰는 국면 | 실제 구현과 빠른 판정이 필요한 실행 단계에 적합함 | 규칙을 설계하고 표현하는 단계에 적합함 |

> 요약: DFA와 NFA가 인식하는 언어 범위는 정규 언어로 동일하지만, DFA는 실행 단순성과 판정 속도에서, NFA는 설계 표현력에서 강점을 가지므로 설계는 NFA로 작성하고 실행은 DFA로 변환해 옮기는 판단이 실무에서 흔함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 집합 $Q$ | 오토마타가 가질 수 있는 조건 전체이며, 상태 수만큼 실행 중 분기 지점이 늘어남 |
| 입력 알파벳 $\Sigma$ | 한 번에 소비하는 입력 기호 종류이며, 전이함수가 빠짐없이 정의해야 할 입력 범위를 정함 |
| 전이함수 $\delta$ | 현재 상태와 입력으로 다음 상태를 정하는 규칙이며, DFA는 $\delta: Q \times \Sigma \to Q$처럼 결과가 상태 하나이지만 NFA는 $\delta: Q \times (\Sigma \cup \{\epsilon\}) \to 2^Q$처럼 결과가 상태 집합임 |
| 시작 상태 $q_0$ | 입력을 읽기 시작하는 단일 상태이며, DFA와 NFA 모두 하나만 둠 |
| 수용 상태 집합 $F$ | 입력을 모두 읽은 뒤 도달한 상태가 속하면 문자열을 수용으로 판정하는 기준이며, NFA는 동시에 열어둔 여러 상태 중 하나만 $F$에 속해도 수용으로 판정함 |

```text
+----------+      +----------+      +----------+
| 시작상태 | ---> | 전이함수 | ---> | 수용상태 |
| (q0)     |      | (delta)  |      | 집합(F)  |
+----------+      +----------+      +----------+
                        |
                        v
                  +----------+
                  | 상태집합(Q)       |
                  | 입력알파벳(Sigma) |
                  +----------+
```

> 요약: $Q, \Sigma, \delta, q_0, F$ 다섯 요소 중 전이함수 $\delta$의 반환 형태(상태 하나 대 상태 집합)가 Ⅲ에서 본 실행 복잡도 차이의 실제 근거임.

## Ⅴ. 원리 및 절차 흐름도

```text
+------------+      +------------+      +------------+      +------------+
| NFA구조확인 | ---> |부분집합구성 | ---> | 완전성검증  | ---> | DFA전이표  |
+------------+      +------------+      +------------+      +------------+
```

1. **NFA 구조 확인**: 설계 단계에서 만든 NFA의 상태 집합, 전이함수, $\epsilon$ 전이 대상을 확인함
2. **부분집합 구성(subset construction)**: $\epsilon$-closure로 $\epsilon$ 전이를 먼저 접어 없앤 뒤, 동시에 도달 가능한 NFA 상태 집합 하나하나를 DFA의 상태 하나로 묶음
3. **완전성 검증**: 새로 만든 각 DFA 상태에서 알파벳 전체에 대한 전이가 빠짐없이 정의됐는지 확인하고, 묶인 NFA 상태 중 수용 상태를 하나라도 포함하면 해당 DFA 상태를 수용 상태로 표시함
4. **DFA 전이표 반환**: 실행에 바로 쓸 수 있는 결정적 전이표와 수용 상태 집합을 산출물로 내보냄

## Ⅵ. 실무 적용 및 유의점

1. 어휘 분석기(lexical analyzer)나 정규식 엔진처럼 실행 속도가 중요한 곳은 설계 단계의 NFA를 부분집합 구성법으로 DFA로 변환해 배치하되, 상태 수가 최악의 경우 $2^n$까지 늘어날 수 있으므로 변환 후 상태 수와 최소화(minimization)로 줄어든 상태 수를 함께 확인함
2. 통신 프로토콜이나 트랜잭션 상태 검증처럼 규칙이 고정되고 빠른 판정이 우선인 경우는 처음부터 DFA로 설계해 정의되지 않은 입력에 대한 전이 누락이 없는지 점검하고, 상태와 입력 조합 커버리지로 전이표 완전성을 확인함

## Ⅶ. 결론

정규 언어 문제는 설계 표현력이 필요하면 NFA로 규칙을 세우고 실행 속도와 판정 단순성이 필요하면 부분집합 구성법으로 DFA로 변환해 배치하되, 그 경계는 변환 후 상태 수 증가 폭과 전이표 완전성 검증 결과로 판단함.
