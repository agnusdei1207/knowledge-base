## 미리 알고가기

- 상태(State): 입력 처리 중 시스템이 가질 수 있는 유한한 제어 위치임
- 입력 알파벳: 오토마타가 읽을 수 있는 기호의 집합임
- 전이 함수: 현재 상태와 입력 기호로 다음 상태를 정하는 규칙임
- DFA: 같은 상태와 입력에 대해 다음 상태가 하나로 정해지는 유한 오토마타임
- NFA: 같은 상태와 입력에서 여러 상태 전이와 $\epsilon$-전이를 허용하는 유한 오토마타임
- 정규 언어: 유한 오토마타가 인식하는 문자열 집합임

## 작성 근거(검토용)

- **개요 구성**: 입력 소비, 상태 전이, 수용 판정이 오토마타의 핵심 절차라 정의에 모두 반영함
- **Ⅱ. 특징 선정**: 유한 상태, DFA 단순성, NFA 표현성, NFA-DFA 변환은 DFA·NFA 답안의 중심 판단임
- **Ⅲ 비교축 선정**: 전이 방식, $\epsilon$-전이, 실행 관리, 설계 난이도가 두 모델 선택을 가름
- **Ⅳ 구조 선정**: 5-튜플은 오토마타 설명의 표준 구성이라 기호와 역할을 표로 정리함
- **Ⅵ 적용 선정**: 정규 표현식과 중첩 문법 한계는 실무 적용과 오토마타 인식 범위를 함께 보여줌

## Ⅰ. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열을 순차적으로 읽은 뒤 현재 상태가 수용 상태인지로 언어 포함 여부를 판정하는 계산 모델임
- **배경/필요성**: 입력 흐름의 규칙 준수를 형식적으로 판단하기 위해 상태 전이 모델이 필요함

## Ⅱ. 특징

- 유한한 상태만 사용해 정규 언어의 수용 여부를 판정함
- DFA는 실행 경로가 하나라 구현과 실행이 단순함
- NFA는 규칙 표현이 간결하지만 실행 시 상태 집합 추적이 필요함
- 모든 NFA는 같은 언어를 인식하는 DFA로 변환됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 결정적 유한 오토마타 (DFA) | 비결정적 유한 오토마타 (NFA) |
|:---|:---|:---|
| 전이 방식 | 현재 상태와 입력마다 하나의 다음 상태 | 가능한 다음 상태의 집합 |
| $\epsilon$-전이 | 허용하지 않음 | 허용 가능 |
| 실행 관리 | 단일 현재 상태 추적 | 상태 집합 추적 |
| 설계 난이도 | 상태 수 증가 위험이 있음 | 규칙 표현이 간결함 |
| 적용 시점 | 실행 엔진·매칭 실행환경 | 규칙 명세·변환 전 모델 |

> 요약: DFA와 NFA의 표현력은 같지만 설계 편의는 NFA, 실행 단순성은 DFA가 유리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 기호 | 설명 |
|:---|:---|:---|
| 상태 집합 | $Q$ | 오토마타가 가질 수 있는 유한 상태 모음임 |
| 입력 알파벳 | $\Sigma$ | 입력 문자열을 구성하는 기호 집합임 |
| 전이 함수 | $\delta$ | 현재 상태와 입력을 다음 상태로 대응시킴 |
| 시작 상태 | $q_0$ | 입력 처리 전의 초기 상태임 |
| 수용 상태 집합 | $F$ | 입력 종료 후 도달하면 문자열을 수용하는 상태 집합임 |

```text
[ 오토마타 구조 ]
M = (Q, Sigma, delta, q0, F)
입력 기호 -> 현재 상태 -> 전이 함수 -> 다음 상태
최종 상태가 F에 포함 -> 수용
```

> 요약: 오토마타는 5개 구성요소로 입력 처리와 수용 판정을 표현함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 시작 상태   | --> | 입력 소비   | --> | 상태 전이   | --> | 수용 판정   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **시작 상태**: 오토마타를 $q_0$에 두고 입력 문자열을 준비함
2. **입력 소비**: 기호를 왼쪽부터 하나씩 읽음
3. **상태 전이**: $\delta$에 따라 다음 상태 또는 상태 집합으로 이동함
4. **수용 판정**: 입력 종료 후 현재 상태가 $F$에 포함되면 수용함

> 요약: 오토마타는 입력을 모두 소비한 뒤 현재 상태가 수용 집합인지로 문자열을 판정함.

## Ⅵ. 실무 적용 및 유의점

1. 정규 표현식 엔진은 패턴을 NFA로 표현한 뒤 DFA나 상태 집합 시뮬레이션으로 실행하고 매칭 시간과 상태 수로 검증함
2. 중첩 괄호처럼 스택이 필요한 문법은 유한 오토마타만으로 부족하므로 PDA나 파서를 쓰고 오류 검출률로 확인함

## Ⅶ. 결론

- 오토마타 이론은 정규 언어 인식과 상태 전이 검증의 기초이므로, DFA·NFA의 표현력 동등성을 전제하고 설계 편의와 실행 비용을 선택 기준으로 삼아야 함
