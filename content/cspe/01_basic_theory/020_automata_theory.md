# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 컴퓨터나 기계가 외부에서 들어오는 입력(문자열, 신호)을 어떻게 받아들이고, 내부 '상태(State)'를 어떻게 바꿔가며 동작하는지를 수학적으로 추상화한 이론이다.
- **왜 필요한가**: 컴파일러가 소스 코드의 문법이 맞는지 틀린지 파악하거나, 정규표현식이 텍스트를 검색할 때 "이 패턴이 맞다/아니다"를 컴퓨터가 기계적으로 판별할 도면이 필요하기 때문이다.
- **핵심 직관**: 자판기 동전 투입. 현재 '0원 상태'에서 '100원 입력'이 들어오면 '100원 상태'로 이동하고, 버튼이 눌리면 '콜라 배출 상태'로 가는 흐름도 그 자체다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 상태 (State) | 기계가 특정 시점에 기억하고 있는 과거 입력의 결과적 상황 | 자판기 화면에 찍힌 현재 투입 금액 |
| 전이 (Transition) | 입력값을 받아 현재 상태에서 다른 상태로 이동하는 규칙 | 100원을 넣으면 금액 화면이 바뀌는 것 |
| DFA (결정론적 유한 오토마타) | 현재 상태와 입력이 주어지면, 다음으로 갈 상태가 100% 한 곳으로 정해진 빡빡한 기계 | 1+1을 누르면 무조건 2가 나오는 계산기 |
| NFA (비결정론적 유한 오토마타) | 같은 입력을 받아도 갈 수 있는 다음 상태가 여러 개일 수 있고, 입력 없이도 점프(ε-전이) 가능한 유연한 기계 | 갈림길에서 분신술을 써서 양쪽 다 가보는 마법사 |

## 깊이 이해
- **배경·문제의식**: 문자열 "ab*c"가 들어왔을 때, 컴퓨터는 이를 어떻게 인식할까? if-else 문을 수백 개 짜는 건 미친 짓이다. 입력이 들어올 때마다 화살표(전이)를 따라 상태(동그라미)를 이동하다가, 끝났을 때 '수락(Accept) 동그라미'에 있으면 정상이라고 판별하는 수학 모델을 고안했다.
- **작동 원리**: 유한 오토마타(상태 개수가 유한함)는 두 종류로 나뉜다.
  1. **NFA**: 정규표현식을 바로 기계 모양(상태도)으로 그리기 매우 쉽다. 하지만 갈림길이 여러 개라 컴퓨터가 코드로 돌리려면 백트래킹(되돌아가기)을 해야 해서 연산이 느리다.
  2. **DFA**: NFA에서 애매한 갈림길을 싹 다 합치고 정리해서, 어떤 입력이 와도 갈 길이 딱 1개뿐이게 만든 튜닝 버전이다. 만들긴 복잡하지만 한 번 만들면 코드로 돌릴 때 갈림길이 없으니 빛의 속도(O(N))로 검색한다.
- **비유**: NFA는 스케치북에 대충 쓱쓱 그린 초안 설계도(사람이 보기 편함)라면, DFA는 그 초안을 공장 라인에 얹기 위해 갈림길을 다 통일해 버린 확정형 캐드(CAD) 도면(기계가 보기 편함)이다.
- **구체 예시**: `(a|b)*abb` 라는 정규표현식을 짤 때 시스템 내부에서는 이 수식을 NFA로 먼저 변환하고, 컴퓨터가 고속으로 텍스트를 찾기 위해 다시 NFA를 DFA로 자동 변환(부분집합 구성법)하여 탐색 엔진을 돌린다.
- **흔한 오해·주의점**: NFA가 갈림길(분신술)이 있어서 성능이 DFA보다 훨씬 뛰어난 기계라고 착각하기 쉽다. 하지만 촘스키 계층에 따르면 DFA와 NFA는 수학적으로 완전히 동급(인식할 수 있는 언어의 범위가 동일함)이며 서로 변환이 100% 가능하다. 표현의 유연성 차이일 뿐이다.

## 연결 개념
- 컴파일러 어휘 분석 (Lexical Analysis) (DFA가 실무에서 가장 많이 쓰이는 곳)
- 정규 언어 / 정규 표현식 (오토마타가 인식하는 대상)
- 튜링 머신 (메모리가 무한대인, 오토마타의 궁극적 최종 진화 형태)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 컴퓨터가 입력 기호열(문자열 등)을 받아들이고 내부 상태를 전이(Transition)하며 해당 패턴을 수락(Accept)할지 결정하는 추상 수학 모델.
> 2. **가치**: 컴파일러의 어휘 분석(Scanner) 및 정규표현식(Regex) 매칭 엔진이 O(N) 고속으로 텍스트를 검증하는 내부 아키텍처로 작동.
> 3. **판단 포인트**: 사람이 설계하기 쉬운 비결정론(NFA) 모델을 컴퓨터가 고속 연산하기 쉬운 결정론(DFA) 모델로 환원(부분집합 구성법)하는 전이 설계가 구현의 핵심.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 유한 상태 기계(FSM)의 2대 축 비교 분석 | DFA(1:1 확정 전이)와 NFA(1:N 유연 전이, ε-전이) 매핑 차이 | NFA가 DFA보다 더 많은 언어를 인식한다는 치명적 오해 |
| 컴파일러 및 정규표현식 파이프라인 이해 | 정규표현식 -> NFA 변환(Thompson) -> DFA 변환(Subset) 메커니즘 | 추상적 수학 기호만 나열하고 실무 응용처 부재 |

> 요약: DFA와 NFA가 수학적으로 동치(Equivalent)임을 명시하고, 실무 검색 엔진에서 둘을 연계(NFA로 설계 후 DFA로 변환)해 쓰는 이유를 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 유한한 개수의 상태(State)와 입력 기호(Symbol), 그리고 이들 간의 전이 규칙(Transition)을 수학적 5원소 튜플로 정의한 추상 기계
- 배경: 복잡한 텍스트 패턴 매칭이나 소스 코드 구문 판별 시, 하드코딩된 분기문(if-else)에 의존하면 유지보수와 복잡도(O(N^2)) 제어 불가능
- 필요성: 정규 언어(Regular Language)를 컴퓨터가 백트래킹 오버헤드 없이 스캔 한 번(O(N))에 완벽히 식별해 내는 자동화 스캐너(Scanner) 아키텍처 도입 필수

---

## Ⅱ. 구조 및 구성요소

```text
정규표현식 입력 -> [톰슨 구조: NFA 생성] -> [부분집합 구성법: DFA 변환] -> [상태 축소: 최소 DFA] -> O(N) 스캔 판독기
```

| 구성요소 (5튜플) | 역할 | 특이사항 |
|:---|:---|:---|
| 유한 상태 집합 (Q) | 기계가 가질 수 있는 모든 노드(상태)의 모음 | 원 개수가 무한정 늘어날 수 없음 (유한 기계 제약) |
| 입력 알파벳 (Σ) | 기계가 외부에서 읽어 들일 수 있는 기호들의 집합 | 바이너리(0,1) 또는 ASCII 텍스트 심볼 단위 |
| 상태 전이 함수 (δ) | 현재 상태 Q와 입력 Σ를 받아 다음 상태 Q'로 이동하는 매핑 룰 | 핵심 엔진 (DFA는 단일 Q' 반환, NFA는 집합 Q' 반환) |
| 시작(q0) / 수락(F) 상태 | 입력 시퀀스 런칭 포인트 및 최종적으로 올바른 패턴임을 인가하는 승인 지점 | 수락 노드 도달 시 True, 못 미치고 입력 종료 시 False |

> 요약: 오토마타는 5개의 수학 튜플 구조체로 모델링되어, 입력 심볼을 화살표 규칙에 맞춰 순차적으로 소화하는 상태 변이 기계다.

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 스트림(문자열) 진입 -> 현재 상태 매칭 -> δ함수 기반 다음 상태 점프 -> 스트림 소진 검사 -> 수락/거절 반환
```

- 1단계 [시작 및 주입]: 오토마타 포인터를 초기 시작 상태(q0)에 맞추고 입력 문자열 스트림을 1바이트씩 스캔 준비
- 2단계 [상태 전이 확정(DFA)]: 입력 기호를 읽어 전이 함수 매핑 테이블을 룩업(Lookup)하여 다음 이동할 단일 상태 노드로 즉각 점프
- 3단계 [상태 분기 전이(NFA)]: 여러 갈래 길이 있거나 ε(빈 문자열) 전이가 허용된 경우, 가능한 모든 상태로 분신을 쪼개어 가상 동시 탐색(백트래킹)
- 4단계 [종료 판별]: 입력 스트림이 모두 소진되었을 때, 멈춘 현재 포인터(들) 중 하나라도 수락 상태(F) 집합 안에 존재하면 패턴 일치(Accept) 리턴

> 요약: 결정론 기계는 한 길만 직진하여 O(N)에 끝내고, 비결정론 기계는 분기점마다 복수의 가능성을 시뮬레이션하여 탐색한다.

## Ⅳ. 특징
- 수학적 동치성(Equivalence): 촘스키 계층 상 DFA와 NFA는 완전히 동일한 언어 클래스(정규 언어, Type-3)만 인식 가능하며, 성능 우열이 아닌 설계 관점 유연성 차이만 존재
- 메모리 한계 극복 불가: 무한히 증가하는 '괄호 쌍 맞추기 `(a^n b^n)`' 같은 문맥 자유 언어(Context-Free)는 기억(Stack) 장치가 없어 절대 인식 불가 (푸시다운 오토마타 필요)
- 고속 렌더링 스루풋: DFA로 완전히 변환 및 최소화(Minimization)가 완료된 상태 테이블 매트릭스는 분기문 분할 없이 CPU 캐시 히트율을 극대화하여 스캔 성능 고도화

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | DFA (결정론적 유한 오토마타) | NFA (비결정론적 유한 오토마타) | 설계 아키텍처 선택 기준 |
|:---|:---|:---|:---|
| 상태 전이 결정성 | 입력 1개당 다음 상태 경로 100% 확정 (1:1 매핑) | 다수 경로 존재 및 ε(입력 없는 공전) 점프 허용 (1:N) | 매칭 수행 주체(컴퓨터 vs 사람) |
| 실행 시간 복잡도 | 텍스트 길이 N 기준 정확히 O(N) 스캔 완료 | 다중 탐색(백트래킹) 발생으로 최악 시 O(2^N) 지연 | 실시간 대용량 로그 검색 스루풋 요건 |
| 구현 및 테이블 크기 | 모든 가능 경로를 개별 노드로 쪼개어 상태 수가 O(2^Q) 폭증 가능 | 복잡한 정규식을 직관적인 극소수 노드로 압축 매핑 표현 | 임베디드 메모리 등 가용 캐시 크기 제약 |

> 요약: 정규표현식을 처음 엔진에 입력(컴파일)할 때는 직관적이고 가벼운 NFA를 쓰고, 이를 대용량 트래픽 런타임에 실행할 때는 O(N) 스루풋을 보장하는 DFA로 변환하여 쓴다.

**리스크·대응:**
- DFA 상태 폭발(State Explosion): NFA에서 DFA로 변환(부분집합 구성법) 시 최악의 경우 노드 수가 2^N개로 지수 폭발해 메모리 붕괴 → 호프크로프트(Hopcroft) 알고리즘 등 상태 최소화(Minimization) 로직을 거쳐 잉여 중복 상태 강제 압축
- NFA 정규표현식 백트래킹 마비(ReDoS): 복잡한 NFA 기반 검색기(예: PCRE 엔진)에 악의적 문자열 주입 시 백트래킹 무한 늪에 빠져 서비스 거부 장애 → 구글 RE2 엔진처럼 무조건 NFA를 DFA 매트릭스로 컴파일한 뒤 선형 시간 매칭으로 차단

**도입 후 점검 지표:**
- 텍스트 파싱 처리량: Giga바이트 단위의 원시 로그 파일(Access Log 등) 패턴 스캔 시, 정규식 엔진의 CPU 점유율이 임계치 초과 없이 선형 시간 O(N) 이내 종료 여부
- 컴파일 안정성: 신규 추가된 라우팅 패턴 정규식이 내부 오토마타로 컴파일될 때(NFA->DFA), 생성된 상태 테이블 배열 크기가 캐시 메모리를 오버플로우하지 않는지 프로파일링

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 렉시컬 분석기(Lexer): Flex / Lex 도구 내부에서, 프로그래밍 소스 코드 텍스트 덩어리를 받아 예약어(if, while), 변수명, 기호를 토큰(Token) 단위로 고속 O(N) 분해 시 DFA 상태 기계 적용
2. WAF(웹 방화벽) 및 IDS 보안 룰 엔진: SQL Injection이나 XSS 같은 수만 개의 공격 시그니처 정규식 패턴을 하나의 거대한 결정론적 DFA 룩업 테이블로 합쳐 인바운드 트래픽 초고속 실시간 필터링
3. 스마트 컨트랙트 및 IoT 상태 전이 검증: 기기의 허용되지 않은 비정상적 상태 점프(예: 결제되지 않았는데 배출 상태로 이동)를 5튜플 오토마타 모델 체크 툴로 수학적 사전 검증하여 오작동 결함 원천 봉쇄

**결론:**
- 기술사 판단: FSM(유한 상태 기계) 아키텍처 적용 시 단순히 정규식을 쓰는 데 그치지 않고, 내부 엔진이 NFA 백트래킹(예: Java Regex)으로 도는지 DFA 선형 스캔(예: RE2)으로 도는지 파악해 ReDoS 취약점을 아키텍처 단에서 통제해야 한다.
- 향후 방향: 단순 정규 문자열 검사를 넘어, 메모리 스택 큐브를 탑재한 푸시다운 오토마타(PDA)와 완전체인 튜링 머신(Turing Machine) 모델로 나아가 자연어 문맥 처리 및 범용 인공지능 LLM 검증 논리로 확장 및 계승 중이다.
