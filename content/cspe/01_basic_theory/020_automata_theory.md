# 오토마타 이론 - DFA·NFA (Automata Theory)

## 1. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열을 상태와 전이 규칙으로 처리해 어떤 언어를 인식할 수 있는지 분석하는 형식 계산 모델 이론이다.
- **배경/필요성**: 문자열 인식 로직을 구현체마다 임의로 만들면 처리 가능한 언어 범위와 정확성을 증명하기 어렵기 때문에, 상태 전이 기반의 형식 모델이 필요하다.

컴파일러 어휘 분석, 정규 표현식 처리, 프로토콜 검증은 오토마타 이론을 기반으로 한다.

## 2. 특징 및 비교

| 구분 | DFA | NFA |
|---|---|---|
| 전이 방식 | 상태와 입력마다 다음 상태가 하나 | 여러 다음 상태 또는 epsilon 전이 가능 |
| 실행 관점 | 결정적 | 비결정적 |
| 표현 편의성 | 상대적으로 복잡할 수 있음 | 패턴 표현이 간결함 |
| 인식 언어 | 정규 언어 | 정규 언어 |
| 구현 | 직접 실행 쉬움 | DFA 변환 또는 시뮬레이션 필요 |

DFA와 NFA는 표현 방식은 다르지만 인식 가능한 언어의 범위는 같다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| 알파벳 | 입력 기호 집합 | 문자·토큰 단위 |
| 상태 집합 | 처리 중 가능한 내부 상태 | 유한 개수 |
| 시작 상태 | 입력 처리 시작점 | 초기 조건 |
| 전이 함수 | 상태와 입력에 따른 다음 상태 | 인식 규칙 |
| 수용 상태 | 입력 종료 후 승인 상태 | 언어 수용 여부 |

```text
입력 문자열 -> 시작 상태 -> 전이 함수 반복 -> 수용 상태 여부 판단
```

## 4. 문제점 및 개선방안

1. **상태 폭발**
   - NFA를 DFA로 변환할 때 상태 수가 지수적으로 증가할 수 있다.
   - **개선방안**: lazy DFA, NFA 직접 시뮬레이션, DFA 최소화를 적용한다.

2. **표현력 한계**
   - 유한 오토마타는 중첩 구조나 개수 일치 같은 정규 언어 밖의 패턴을 표현하지 못한다.
   - **개선방안**: 문맥 자유 문법, PDA, 파서로 처리 범위를 분리한다.

3. **전이 정의 누락**
   - 일부 상태·입력 조합의 전이가 빠지면 구현에서 예외나 잘못된 판정이 발생한다.
   - **개선방안**: sink state 추가, 전이표 커버리지 테스트를 수행한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 컴파일러 어휘 분석 | 토큰 패턴을 정규식과 DFA로 변환해 스캔 | 토큰 인식률, 스캔 시간 |
| 입력 검증 | 이메일, 식별자, 프로토콜 필드 패턴 검증 | 오탐·미탐, 매칭 시간 |
| 보안 필터링 | 정규식 기반 로그·패킷 패턴 탐지 | 처리량, ReDoS 여부 |

## 6. 결론

오토마타 이론은 문자열 인식과 계산 모델의 표현 한계를 설명하는 기초 이론이다. DFA·NFA는 정규 언어 인식에 동등한 능력을 갖지만, 상태 수와 구현 방식이 다르므로 표현 편의성과 실행 효율을 함께 판단해야 한다.
