## 미리 알고가기

- 상태: 입력 처리 중 시스템이 기억하는 현재 조건임
- 전이 함수: 현재 상태와 입력 기호로 다음 상태를 정하는 규칙임
- 정규 언어: 유한 오토마타로 판정할 수 있는 문자열 집합임
- DFA: 같은 상태와 입력에서 다음 상태가 하나로 정해지는 오토마타임
- NFA: 같은 상태와 입력에서 여러 다음 상태를 허용할 수 있는 오토마타임
- $\epsilon$ 전이: 입력을 소비하지 않고 상태만 이동하는 전이임

## Ⅰ. 개요

- **정의/개념**: 오토마타는 입력 기호를 순서대로 읽으며 상태를 바꾸고, 마지막 상태가 수용 상태인지로 문자열의 규칙 만족 여부를 판정하는 계산 모델임
- **배경/필요성**: 문자열 패턴 검사, 어휘 분석, 프로토콜 검증은 입력 흐름이 규칙을 따르는지 확인해야 함. 상태와 전이로 표현하면 누락된 입력과 잘못된 이동을 검토하기 쉬움

## Ⅱ. 특징

- 상태와 전이로 규칙을 표현하므로 입력별 동작을 표나 그래프로 확인할 수 있음
- 유한 상태만 사용하므로 정규 언어 범위의 패턴을 판정함
- DFA는 실행 경로가 하나라 구현이 단순하고 빠름
- NFA는 여러 가능성을 열어둘 수 있어 복잡한 패턴을 간결하게 표현함

## Ⅲ. 종류 및 비교

| 판단 기준 | DFA | NFA |
|:---|:---|:---|
| 다음 상태 | 항상 하나 | 여러 개 가능 |
| $\epsilon$ 전이 | 없음 | 가능 |
| 실행 방식 | 현재 상태 하나만 추적 | 가능한 상태 집합을 추적 |
| 강점 | 실행 단순성, 빠른 판정 | 설계 표현력 |
| 주 사용 | 구현 단계 | 규칙 설계 단계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 집합 $Q$ | 오토마타가 가질 수 있는 모든 상태임 |
| 입력 알파벳 $\Sigma$ | 처리할 수 있는 입력 기호의 집합임 |
| 전이 함수 $\delta$ | 현재 상태와 입력으로 다음 상태를 정하는 규칙임 |
| 시작 상태 $q_0$ | 입력을 읽기 시작하는 상태임 |
| 수용 상태 집합 $F$ | 입력 종료 후 도달하면 수용으로 판정하는 상태 집합임 |

```text
+-----------+     +-----------+     +-----------+
| 시작 상태 | --> | 전이 함수 | --> | 수용 상태 |
+-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 시작 상태 | --> | 입력 읽기 | --> | 상태 전이 | --> | 수용 판정 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 시작 상태에서 첫 입력 기호를 읽음
2. 전이 함수에 따라 다음 상태로 이동함
3. 모든 입력을 읽을 때까지 반복함
4. 마지막 상태가 수용 상태이면 문자열을 받아들임

## Ⅵ. 실무 적용 및 유의점

1. 정규식 엔진이나 어휘 분석기를 설계할 때는 NFA로 규칙을 표현하고 DFA로 변환해 실행 성능을 확인하는 방식이 실용적임
2. 괄호 중첩 등 임의 깊이의 기억이 필요한 패턴은 유한 오토마타만으로 부족하므로 스택을 쓰는 모델이나 파서가 필요함

## Ⅶ. 결론

- 오토마타는 입력 규칙을 상태와 전이로 검증하는 모델이며, DFA는 실행에, NFA는 표현에 강점이 있음
