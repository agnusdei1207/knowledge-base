# 오토마타 이론 - DFA·NFA (Automata Theory)

## 미리 알고가기

- **상태(state)와 전이(transition)**: 상태는 지금까지 읽은 입력을 한 덩어리로 요약한 "기억"이고, 전이는 지금 상태에서 글자 하나를 읽었을 때 어느 상태로 옮겨 갈지 정한 화살표다. 자판기가 동전 순서는 잊고 "지금까지 400원"만 기억하면 되는 것과 같다.
- **정규 언어(regular language)**: 유한 오토마타로 인식되는 문자열 집합. "a가 몇 개 오든 그 뒤에 b" 같은 반복·선택 패턴은 되지만, "여는 괄호 수와 닫는 괄호 수가 같다"처럼 개수를 세어 맞추는 패턴은 안 된다.
- **epsilon(ε) 전이**: 입력을 한 글자도 읽지 않고 공짜로 상태만 건너뛰는 이동. NFA에서만 허용된다.

## 1. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열을 한 글자씩 읽으며 상태를 옮겨 가다가, 다 읽었을 때 도착한 상태가 수용 상태인지로 그 문자열이 특정 언어(패턴 집합)에 속하는지 판정하는 계산 모델 이론이다.
- **배경/필요성**: 이메일이 형식에 맞는지, 소스코드에서 어디까지가 낱말 하나(토큰)인지처럼 "이 문자열이 정해진 패턴에 맞나"를 판단하는 일은 어디에나 있다. 그런데 이걸 그때그때 if-else로 손수 짜면 규칙이 조금만 얽혀도 맞게 짰는지 확신할 수 없고, 애초에 이 방식으로는 표현조차 못 하는 패턴이 무엇인지도 알 수 없다. 오토마타는 이 판단을 "상태 몇 개와 화살표(전이)"라는 그림 하나로 옮겨, 입력을 한 글자씩 따라가기만 하면 기계적으로 통과·거부가 갈리게 하고, 나아가 이 그림으로 표현할 수 있는 패턴의 한계까지 수학적으로 그어 준다.

## 2. 특징 및 비교

DFA(Deterministic Finite Automaton, 결정적 유한 오토마타)와 NFA(Nondeterministic Finite Automaton, 비결정적 유한 오토마타)는 그리는 방식만 다를 뿐 인식할 수 있는 언어 범위는 똑같이 정규 언어다. 갈리는 지점은 "한 갈림길에서 갈 곳이 하나로 정해져 있느냐"다.

| 구분 | DFA | NFA |
|:---|:---|:---|
| 갈림길에서 다음 상태 | 상태·입력마다 딱 하나로 정해짐 | 여러 개일 수도, ε로 공짜 이동도 가능 |
| 실행 관점 | 표지판 따라 한 길로 쭉 감 | 여러 갈래를 동시에 들고 가야 함 |
| 그리기 편의성 | 상태 수가 불어나 장황해지기 쉬움 | 패턴을 짧고 간결하게 그림 |
| 인식 언어 | 정규 언어 | 정규 언어 (DFA와 동일) |
| 실행 방식 | 그대로 바로 실행 | DFA로 변환하거나 상태 집합을 함께 추적 |

> 요약: 표현력은 같고, NFA는 그리기 쉬운 대신 실행하려면 결국 DFA로 풀어야 한다.

DFA는 어느 상태에서 어떤 글자를 읽든 갈 곳이 하나뿐이라, 갈림길마다 "이쪽으로 가라"는 표지판이 붙은 미로와 같다. 헤맬 일 없이 한 길로 쭉 따라가면 끝나므로 실행이 단순하다. NFA는 같은 글자에 갈 곳이 여러 개이거나 ε로 그냥 건너뛸 수 있어, 마치 갈림길에서 여러 갈래를 한꺼번에 밟아 보는 미로와 같다. 사람이 패턴을 그릴 땐 이 편이 훨씬 짧고 직관적이지만, 컴퓨터가 실제로 돌리려면 "지금 있을 수 있는 상태 전부"를 하나의 상태로 뭉쳐 DFA로 바꿔야 한다.

## 3. 구성요소/구조

오토마타 하나는 다섯 요소로 정해진다. 이진 문자열이 1로 끝나는지 검사하는 작은 DFA를 예로 보면, 상태는 q0(아직 1로 안 끝남)과 q1(1로 끝남) 둘이면 충분하다.

| 구성요소 | 하는 일 | 왜 중요한가 |
|:---|:---|:---|
| 알파벳(Alphabet) | 읽을 수 있는 입력 기호 집합 | 문자·토큰의 단위를 못 박음 |
| 상태 집합(States) | 처리 중 놓일 수 있는 내부 상태 | 반드시 유한 개 |
| 시작 상태(Start) | 입력을 읽기 시작하는 자리 | 판정의 출발점 |
| 전이 함수(Transition) | 상태·입력에 따라 갈 다음 상태 | 인식 규칙 그 자체 |
| 수용 상태(Accept) | 입력이 끝났을 때 통과로 볼 상태 | 언어에 속하는지 판정 |

```text
   입력: "1 0 1"
     |
     v
 현재 q0 --읽음 '1'--> 전이 d(q0,'1') = q1
 현재 q1 --읽음 '0'--> 전이 d(q1,'0') = q0
 현재 q0 --읽음 '1'--> 전이 d(q0,'1') = q1
     |
     v
 입력 끝: 도착 상태 q1이 수용 상태인가? --> 예 --> 수용(Accept)
```

> 요약: 시작 상태에서 글자마다 전이 함수로 상태를 갈아타다가, 마지막 상태가 수용 상태면 그 문자열을 언어의 일원으로 받아들인다.

전이 함수가 상태·입력의 모든 조합을 빠짐없이 덮어야 이 판정이 흔들리지 않는다. DFA는 조합마다 갈 곳이 하나로 정해져 있어 바로 이 표를 따라가면 되고, 정규식·어휘 분석기·프로토콜 상태 검증이 모두 같은 그림을 공유하는 이유도 여기에 있다.

## 4. 문제점 및 개선방안

1. **상태 폭발**: 간결한 NFA를 DFA로 바꾸면, "지금 있을 수 있는 상태 묶음"을 하나하나 새 상태로 만들다 상태 수가 원본의 지수배까지 불어날 수 있다.
   - **개선방안**: 실행 중 실제로 닿는 상태 묶음만 그때그때 만드는 lazy DFA를 쓰거나, NFA를 변환 없이 상태 집합째 시뮬레이션하고, 만든 DFA는 최소화로 중복 상태를 합친다. (확인: 변환 후 상태 수, 매칭 시간)

2. **표현력의 한계**: 유한 오토마타는 상태가 유한하고 과거를 세어 두는 저장소가 없어, 괄호 짝 맞추기나 개수 일치 같은 정규 언어 밖의 패턴은 원리적으로 표현하지 못한다.
   - **개선방안**: 이런 패턴은 스택을 덧붙인 PDA(Pushdown Automaton, 하향식 오토마타)와 문맥 자유 문법·파서로 넘겨 처리 범위를 나눈다. (확인: 대상 언어가 정규/문맥자유 중 어디에 속하는지)

3. **전이 정의 누락**: 일부 상태·입력 조합의 전이를 빠뜨리면, 실행 중 그 조합을 만났을 때 예외가 나거나 엉뚱한 판정이 나온다.
   - **개선방안**: 어디에도 안 맞는 입력을 모아 보내는 거부용 sink state를 두어 전이표를 빈칸 없이 채우고, 조합 커버리지 테스트로 누락을 잡는다. (확인: 전이표 빈칸 수 0, 커버리지)

## 5. 실무 적용 사례

| 적용 영역 | 어떻게 쓰나 | 무엇으로 효과를 확인하나 |
|:---|:---|:---|
| 컴파일러 어휘 분석 | 토큰 패턴을 정규식으로 쓴 뒤 DFA로 바꿔 소스를 한 글자씩 스캔 | 토큰 인식 정확도, 스캔 시간 |
| 입력 형식 검증 | 식별자·이메일·프로토콜 필드가 규칙에 맞는지 상태 전이로 판정 | 오탐·미탐률, 매칭 시간 |
| 보안 패턴 탐지 | 로그·패킷을 정규식 기반으로 훑어 악성 패턴을 걸러 냄 | 처리량, ReDoS(Regular expression Denial of Service) 위험 |

> 요약: 정규식으로 그린 패턴을 DFA로 실행하는 것이 공통 골격이고, 확인 지표는 인식 정확도와 매칭 시간·안정성으로 모인다.

## 6. 결론

오토마타 이론은 문자열 판정을 상태와 전이의 그림으로 옮겨, 무엇을 인식할 수 있고 무엇은 원리적으로 못 하는지까지 그어 주는 계산의 기초 이론이다. DFA와 NFA는 인식 능력이 같으므로, 실무의 선택은 "어느 쪽이 더 강하냐"가 아니라 패턴을 간결하게 그릴 땐 NFA로 쓰고 실행 단계에서 DFA로 풀되 상태 폭발을 최소화·lazy 변환으로 눌러 두는 쪽으로 좁혀진다. 그리고 괄호 짝처럼 정규 언어를 벗어나는 패턴을 만나면 유한 오토마타를 고집하지 말고 PDA·파서로 경계를 넘겨야 한다.
