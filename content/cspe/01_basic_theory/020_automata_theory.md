## 미리 알고가기

- 상태(State): 특정 시점에서의 시스템 조건이나 제어 위치를 나타내는 유한한 값들의 집합임
- 전이 함수($Transition$ $Function$): 현재 상태와 입력 기호를 입력받아 다음 상태를 결정하는 동작 규칙임
- 결정적 유한 오토마타(DFA): 동일한 상태와 입력에 대해 전이되는 다음 상태가 오직 하나인 오토마타임
- 비결정적 유한 오토마타(NFA): 동일한 상태와 입력에 대해 여러 개의 다음 상태로 전이되거나, 입력 없이 상태가 변하는($\epsilon$-전이) 구조를 허용하는 오토마타임

## Ⅰ. 개요

- **정의/개념**: 오토마타 이론은 입력 문자열을 순차적으로 읽으며 미리 정의된 전이 규칙에 따라 상태를 변화시키고, 최종 상태의 수용 여부로 입력의 유효성을 판별하는 추상적인 계산 모델임
- **배경/필요성**: 프로그래밍 언어의 어휘 분석($Lexical$ $Analysis$), 통신 프로토콜의 상태 전이 검증, 정규 표현식 매칭 등 연속적인 입력 흐름이 정해진 규칙을 엄격히 준수하는지 논리적으로 증명하기 위해 사용됨

## Ⅱ. 특징

- 유한한 메모리(상태)를 사용하여 입력의 문법적 정합성을 판단하며, 촘스키 계층($Chomsky$ $Hierarchy$) 중 정규 언어($Regular$ $Language$)를 인식하는 최소 단위의 모델임
- DFA는 실행 경로가 결정론적이어서 구현이 매우 단순하고 빠른 실행 성능을 보장하며, NFA는 설계자가 규칙을 보다 직관적이고 간결하게 표현할 수 있도록 유연성을 제공함
- 모든 NFA는 동일한 언어를 인식하는 DFA로 변환($Subset$ $Construction$)이 가능하므로, 설계의 편의성과 실행의 효율성을 동시에 확보할 수 있는 논리적 기반이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 결정적 유한 오토마타 (DFA) | 비결정적 유한 오토마타 (NFA) |
|:---|:---|:---|
| **상태 전이** | 단일 전이 (유일성) | 다중 전이 (가능성 집합) |
| **공백 전이** | 허용되지 않음 | $\epsilon$-전이 허용 |
| **인식 속도** | 빠름 ($O(n)$) | 느림 (상태 집합 추적 비용) |
| **설계 복잡도** | 상태 수가 많아 설계가 어려움 | 직관적이고 간결한 설계 가능 |
| **적용 시점** | 실제 엔진 구현 및 런타임 | 규칙 명세 및 논리 설계 단계 |

> 요약: 이론적 표현력은 동일하지만, 설계 효율은 NFA가 높고 실행 성능은 DFA가 우수함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 기호 | 설명 |
|:---|:---|:---|
| 상태 집합 | $Q$ | 오토마타가 가질 수 있는 모든 가능한 유한한 상태들의 모음임 |
| 입력 알파벳 | $\Sigma$ | 시스템이 인식하고 처리할 수 있는 유효한 기호들의 집합임 |
| 전이 함수 | $\delta$ | ($Q \times \Sigma \rightarrow Q$) 현재 상태와 입력을 다음 상태로 사상하는 핵심 로직임 |
| 시작 상태 | $q_0$ | 입력을 읽기 전의 초기 상태이며, $Q$의 원소 중 하나임 |
| 종료 상태 집합 | $F$ | 모든 입력을 읽은 후 이 상태에 도달하면 문자열을 '수용'으로 판정하는 집합임 |

```text
[ 오토마타 5-튜플 모델 ]
M = (Q, Σ, δ, q0, F)
- State Transition: (s1) --- 'a' ---> (s2)
- Accepting: Final State in F (Double Circle)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 시작 상태 진입| --> | 입력 기호 소비| --> | 상태 전이 함수| --> | 최종 수용 판정|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **상태 초기화** — 오토마타를 정의된 시작 상태($q_0$)로 설정하고 입력 문자열의 첫 번째 기호를 대기함
2. **기호 읽기** — 문자열에서 기호를 하나씩 순차적으로 읽어 들이며, 입력이 끝날 때까지 처리를 반복함
3. **상태 전이** — 현재 상태와 방금 읽은 기호를 전이 함수($\delta$)에 대입하여 정의된 다음 상태로 전이함 (DFA는 즉시 전이, NFA는 가능한 모든 상태 집합 관리)
4. **결과 수용** — 모든 입력 기호를 소비한 후, 도달한 최종 상태가 수용 상태 집합($F$)에 포함되어 있으면 '수용($Accept$)', 그렇지 않으면 '거부($Reject$)'로 판정함

## Ⅵ. 실무 적용 및 유의점

1. 정규 표현식($Regex$) 엔진 구현 시, 사용자 정의 패턴은 먼저 NFA로 변환하여 설계의 유연성을 확보하고, 실제 대량 문자열 매칭 시에는 이를 DFA로 컴파일하여 매칭 성능을 최적화하는 계층적 접근을 취해야 함
2. 유한 오토마타는 상태가 유한하므로 $a^nb^n$과 같이 무한한 메모리(스택)가 필요한 문맥 자유 언어($CFL$)를 판별할 수 없음을 인지하고, 중첩 괄호 검사 등 복잡한 문법 검증이 필요할 경우 푸시다운 오토마타($PDA$)나 재귀 하강 파서를 도입해야 함

## Ⅶ. 결론

- 오토마타 이론은 입력 데이터의 논리적 무결성을 검증하는 정밀한 계산 도구이며, 설계자는 모델의 인식 한계와 실행 효율성을 명확히 분석하여 시스템의 견고성과 처리 속도를 동시에 달성해야 함
