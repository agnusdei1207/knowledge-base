## 미리 알고가기

- 상태: 입력 처리 중 시스템이 기억하는 현재 조건임
- 전이 함수: 현재 상태와 입력에 따라 다음 상태를 정하는 규칙임
- 정규 언어: 유한 오토마타가 인식할 수 있는 언어 집합임
- $\epsilon$ 전이: 입력 문자를 소비하지 않고 상태만 이동하는 전이임

## Ⅰ. 개요

- **정의/개념**: 오토마타는 입력 기호를 한 글자씩 읽으면서 현재 상태를 바꾸고, 입력을 모두 처리한 뒤 수용 상태 도달 여부로 문자열의 규칙 만족 여부를 판정하는 계산 모델이며 유한 오토마타의 대표 형태가 DFA와 NFA임
- **배경/필요성**: 문자열 패턴 검사, 어휘 분석, 프로토콜 상태 검증처럼 입력 흐름을 규칙대로 통제해야 하는 영역에서는 규칙을 상태와 전이로 분해해 누락 없이 점검할 수 있는 기준이 필요함

## Ⅱ. 특징

- 오토마타는 입력 처리 규칙을 상태와 전이로 고정해 규칙 누락, 예외 입력, 종료 조건을 명시적으로 검증할 수 있게 만듦
- DFA는 현재 상태가 항상 하나라서 구현과 실행 경로가 단순하며, 입력을 순차적으로 빠르게 판정하기에 적합함
- NFA는 한 입력에서 여러 경로를 허용하고 $\epsilon$ 전이도 둘 수 있어 복잡한 패턴을 더 자연스럽게 표현하기 쉬움
- 두 모델은 표현 방식과 실행 방식은 다르지만, 유한 오토마타가 인식할 수 있는 정규 언어 범위는 동일함

## Ⅲ. 종류 및 비교

| 판단 기준 | DFA | NFA |
|:---|:---|:---|
| 다음 상태를 고르는 방식 | 현재 상태와 입력 기호가 주어지면 다음 상태가 하나로 결정됨 | 같은 입력에서도 여러 다음 상태를 동시에 허용할 수 있음 |
| 빈 입력 이동 | 입력을 읽지 않고 이동하는 $\epsilon$ 전이를 두지 않음 | 입력을 소비하지 않고 이동하는 $\epsilon$ 전이를 둘 수 있음 |
| 실행 시 관리해야 할 상태 | 현재 상태 하나만 추적하면 되어 구현이 단순함 | 여러 상태 후보 집합을 함께 관리해야 하므로 실행 로직이 더 복잡함 |
| 주로 쓰는 관점 | 빠른 판정과 코드 구현이 중요할 때 적합함 | 패턴을 자연스럽게 표현하고 설계하는 단계에서 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 집합 | 입력을 어디까지 어떤 조건으로 처리했는지 나타내는 상태들의 모음이며, 상태가 불필요하게 많아지면 구현과 검증 비용이 함께 커짐 |
| 입력 알파벳 | 오토마타가 읽을 수 있는 기호 집합이며, 이 범위를 벗어나는 입력은 별도 예외 처리 규칙을 정의해야 함 |
| 전이 함수 | 현재 상태와 입력 기호를 다음 상태로 연결하는 규칙이며, 빠진 전이가 있으면 일부 입력을 처리하지 못하거나 오류 처리가 모호해짐 |
| 시작 상태와 수용 상태 | 시작 상태는 판정의 출발점이고 수용 상태는 규칙을 만족했다는 종료 조건이며, 입력 종료 시 수용 상태에 있어야 문자열을 받아들임 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 시작 상태 | --> | 입력 기호  | --> | 전이 함수  | --> | 수용 판정  |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상태초기화 | --> | 입력읽기 | --> | 전이적용 | --> | 수용판정 |
+----------+     +----------+     +----------+     +----------+
```

1. **상태초기화**: 정의된 시작 상태에 오토마타를 놓고 입력 처리를 준비함
2. **입력읽기**: 문자열에서 현재 기호를 하나 읽음
3. **전이적용**: 전이 함수에 따라 다음 상태 또는 상태 집합으로 이동함
4. **수용판정**: 입력을 모두 읽은 뒤 수용 상태에 있으면 문자열을 받아들이고 아니면 거부함

## Ⅵ. 실무 적용 및 유의점

1. 컴파일러 어휘 분석은 토큰 규칙을 DFA로 바꿔 빠르게 판정하고 토큰화 정확도와 처리량으로 확인함
2. 프로토콜 상태 검증은 상태 전이로 누락을 막되 상태 수가 과도하게 늘지 않게 관리하고 규칙 위반 탐지율과 메모리 사용량으로 확인함

## Ⅶ. 결론

오토마타 이론의 실무 가치는 복잡한 입력 규칙을 상태와 전이로 고정해 누락 없이 검증하는 데 있으므로, 설계는 표현이 쉬운 형태로 하고 실행은 판정이 안정적인 형태로 옮기는 판단이 중요함.
