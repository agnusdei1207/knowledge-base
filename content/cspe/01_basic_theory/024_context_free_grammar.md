## Ⅰ. 개요
- **정의**: 비단말 기호를 단말·비단말의 조합으로 치환하는 생성 규칙 집합으로, 문맥 자유 언어를 정의하는 문법
- **배경/필요성**: 정규 표현식(023 참조)으로 기술할 수 없는 중첩 구조(괄호 짝, 재귀 구문)를 형식적으로 명세할 수단이 필요함
- **비유**: 문장을 주어·서술어·목적어로 분해하는 국어 문법처럼, 프로그램을 구문 규칙으로 분해하는 도구임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CFG와 정규 문법의 표현력 차이를 설명할 수 있는지 확인 | 4-튜플 정의, BNF 표기, 파스 트리 구성 | 모호한 문법과 모호하지 않은 문법의 구분을 누락하지 말 것 |

> 요약: 재귀적 생성 규칙으로 프로그래밍 언어의 구문 구조를 형식 정의하는 문법 체계임

## Ⅱ. 구성요소
```text
  문법 G = (V, T, P, S)

  S --> A + A        <-- 생성 규칙(P)
  A --> number       <-- 비단말 -> 단말 치환
       |
       v
     파스 트리
      [S]
     / | \
   [A] [+] [A]
    |       |
  number  number
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 비단말 기호(`V`) | 생성 규칙의 좌변에 올 수 있는 치환 가능한 기호 집합 | 문장 성분(주어·목적어) 라벨 |
| 단말 기호(`T`) | 최종 문자열에 나타나는 치환 불가 기호 집합 | 실제로 쓰이는 단어 자체 |
| 생성 규칙(`P`) | 비단말을 단말·비단말 조합으로 치환하는 규칙 모음 | "주어 = 명사 + 조사" 같은 문법 규칙 |
| 시작 기호(`S`) | 유도를 시작하는 최초의 비단말 기호 | 문장 전체를 나타내는 최상위 라벨 |
| 파스 트리 | 유도 과정을 트리로 시각화한 구조, 각 내부 노드가 생성 규칙 적용에 대응함 | 문장을 성분별로 가지치기한 도표 |

> 요약: 비단말·단말·생성 규칙·시작 기호와 파스 트리로 구문 구조를 정의함

## Ⅲ. 절차
```text
  1.문법정의       2.유도           3.파스트리구성   4.모호성검증
  (BNF작성)       (규칙적용)       (트리생성)       (유일성확인)
   |               |               |               |
   +---생성규칙---->+---문자열생성--->+---트리시각화--->+
  V,T,P,S정의     좌측/우측유도    내부노드=규칙    2개이상트리여부
```
- 1단계: 비단말·단말·생성 규칙·시작 기호를 BNF(또는 EBNF) 표기로 정의함
- 2단계: 시작 기호에서 생성 규칙을 반복 적용(좌측 유도 또는 우측 유도)하여 문자열을 생성함
- 3단계: 유도 과정을 파스 트리로 구성하여 구문 구조를 시각화함
- 4단계: 동일 문자열에 대해 파스 트리가 2개 이상 존재하면 모호한 문법으로 판정하고 수정함

> 요약: 문법 정의 → 유도 → 파스 트리 구성 → 모호성 검증의 4단계로 구문을 분석함

## Ⅳ. 문제점
- 문법 모호성: 하나의 문자열에 복수 파스 트리가 존재하면 의미 해석이 비결정적이 됨
- 좌재귀 무한루프: `A -> A + B` 형태의 좌재귀 규칙이 하향식 파서에서 무한 재귀를 유발함
- 구문 분석 복잡도: 범용 CFG 파싱(Earley)은 $O(n^3)$이어서 대규모 입력에서 성능 부담이 됨

> 요약: 모호성·좌재귀·파싱 복잡도가 CFG 활용의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 연산자 우선순위·결합 규칙을 도입하여 모호성을 제거함
2. 중기: 좌재귀를 우재귀로 변환하거나 좌인수분해를 적용하여 LL 파서 적용을 가능하게 함
3. 장기: LR/LALR 파서 생성기(025 참조)를 활용하여 $O(n)$ 시간에 결정적 구문 분석을 수행함

> 요약: 모호성 제거 → 좌재귀 변환 → LR 파서 적용으로 CFG의 한계를 극복함

## Ⅵ. 전망
- 발전 방향: DSL 설계·프로토콜 명세에서 CFG 기반 파서 생성기 활용이 확대되는 추세임
- 기술사적 판단: 컴파일러 구문 분석(025 참조)의 이론적 기반으로서 지속 핵심 역할을 수행함
- 기술사 제언: 문법 설계 시 모호성 여부를 검증하고, 대상 파서 유형에 맞는 문법 변환을 적용해야 함
