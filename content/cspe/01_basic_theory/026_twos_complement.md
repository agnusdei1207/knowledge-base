## Ⅰ. 개요
- 정의: 음수를 표현하기 위해 양수의 모든 비트를 반전시킨 후 1을 더하는 방식임
- 배경/필요성: 뺄셈을 가산기(Adder)만으로 처리하고, +0과 -0의 중복을 제거함
- 출제 의도: 보수의 개념, 음수 변환 과정, 오버플로우 판별 능력 검증

## Ⅱ. 구성요소
- ASCII 구조도
  Positive: 0 0 1 0 ( +2 )
            ↓ (Invert)
  1's Comp: 1 1 0 1
            ↓ (Add 1)
  2's Comp: 1 1 1 0 ( -2 )

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 최상위 비트(MSB) | 부호를 결정하는 비트 (0:양수, 1:음수) | 이정표 |
| 1의 보수 | 0을 1로, 1을 0으로 반전시킨 값 | 거울 이미지 |
| 가산기 (Adder) | 2의 보수를 더하여 뺄셈을 수행하는 장치 | 합산기 |
| 오버플로우 | 연산 결과가 표현 범위를 벗어나는 현상 | 넘침 |
> 요약: 2의 보수는 뺄셈 연산의 하드웨어 구현을 단순화하는 효율적인 수 체계임

## Ⅲ. 절차
- ASCII 흐름도
  [양수] -> [비트 반전] -> [+1 수행] -> [음수 확정] -> [가산기 투입]

1. 비트 반전: 주어진 양수의 모든 비트를 NOT 연산함 (1의 보수)
2. 1 더하기: 반전된 결과에 최하위 비트(LSB)부터 1을 더함
3. 부호 확장: 필요한 자릿수만큼 MSB를 복사하여 확장함
4. 연산 수행: 뺄셈 대상 숫자를 보수화한 뒤 피감수와 더함
> 요약: 'A - B'를 'A + (-B의 2의 보수)'로 변환하여 처리함

## Ⅳ. 문제점
- 비대칭 범위: 8비트 기준 -128~127로, 음수가 양수보다 1개 더 많음
- 오버플로우 발생: 부호가 같은 두 수의 합이 부호 비트를 침범할 위험 존재함

## Ⅴ. 개선방안
- 오버플로우 검출: MSB의 Carry-in과 Carry-out의 XOR 연산으로 감지함
- 자릿수 확장: 연산 전 비트 수를 충분히 늘려(Sign Extension) 범위를 확보함

## Ⅵ. 전망
- 표준 채택: 거의 모든 현대 CPU(x86, ARM 등)에서 기본 정수 연산 방식으로 사용됨
- 효율적 연산: ALU 설계 단순화를 통해 저전력, 고속 연산 장치 구현의 핵심이 됨
