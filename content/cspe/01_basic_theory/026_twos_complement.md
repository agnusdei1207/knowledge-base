## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 2의 보수(Two's Complement)는 음수를 이진수로 표현하는 체계로, **비트를 반전(NOT)시킨 후 1을 더하면** 해당 수의 음수가 된다. 이 방식의 혁신은 **덧셈 회로 하나로 덧셈과 뺄셈을 모두 처리**할 수 있다는 점이다.
> 2. **가치**: 부호-크기(Sign-Magnitude)나 1의 보수와 달리, 2의 보수는 **0의 표현이 하나뿐**이고(-0 문제 없음), 덧셈기만으로 뺄셈이 가능하여 하드웨어가 단순해진다. 현대 CPU의 사실상 유일한 정수 음수 표현 방식이다.
> 3. **융합**: CPU ALU 설계(가산기 하나로 ±연산), 컴파일러(정수 오버플로우 탐지), 보안(정수 오버플로우 취약점), 네트워크(체크섬 계산), 운영체제(커널 에러 코드) 등 정수 연산이 관여하는 모든 영역의 기반이다.

---

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| **2의 보수(Two's Complement)** | 비트 반전(NOT) + 1로 음수를 표현하는 방식. 가산기만으로 ±연산 가능 | "시계 거꾸로 돌리기" |
| **MSB(Most Significant Bit)** | 최상위 비트. 2의 보수에서 0=양수, 1=음수를 나타내는 부호 비트 | "양수/음수 표지판" |
| **오버플로우(Overflow)** | 표현 범위를 초과하여 부호가 뒤집히는 현상. 8비트: $127 + 1 = -128$ | "시계 12 넘기" |
| **부호 확장(Sign Extension)** | 작은 비트 폭의 수를 큰 비트 폭으로 확장할 때 MSB를 복사하는 기법 | "앞자리 빈칸 채우기" |

## Ⅰ. 개요 및 필요성

- **개념**: N비트 2의 보수 체계에서 양수는 일반 이진수와 동일하고, 음수 -X는 X의 모든 비트를 반전(1의 보수)한 후 1을 더한 값이다. MSB(Most Significant Bit)가 0이면 양수, 1이면 음수이다. 8비트 기준 표현 범위는 -128 ~ +127이다.

- **필요성**: 컴퓨터는 뺄셈 전용 회로 없이 `A - B = A + (-B)`로 계산한다. 2의 보수에서 -B를 구하는 비용은 NOT + 1이므로, 기존 가산기(Adder)를 그대로 재활용할 수 있다. 이것이 하드웨어 비용을 극적으로 줄인다.

- **비유**: 2의 보수는 **시계 역회전**과 같다. 12시간 시계에서 "3시간 전"은 "9시간 후"와 같다(12-3=9). 즉, -3 ≡ +9 (mod 12). 2의 보수도 동일한 모듈러 산술 원리이다.

- **등장 배경 및 발전 과정**:
  1. **1940~50년대**: 초기 컴퓨터(ENIAC)는 부호-크기 방식을 사용했으나, -0과 +0의 이중 표현 문제가 있었다.
  2. **1960년대**: IBM System/360이 2의 보수를 채택하면서 업계 표준이 되었다.
  3. **현대**: 모든 CPU(x86, ARM, RISC-V)가 2의 보수를 사용한다. C/Java/Python 등 모든 언어의 정수 연산이 2의 보수 기반이다.

```text
+-----------------------------------------------------------------------+
|        8비트 2의 보수 변환 예시: +5 → -5                              |
+-----------------------------------------------------------------------+
|                                                                       |
|  [Step 1] +5의 이진 표현                                             |
|  +5 = 00000101₂                                                      |
|                                                                       |
|  [Step 2] 모든 비트 반전 (1의 보수)                                  |
|  00000101 → 11111010                                                 |
|                                                                       |
|  [Step 3] 1을 더함 (2의 보수)                                        |
|  11111010 + 1 = 11111011                                             |
|                                                                       |
|  결과: -5 = 11111011₂                                                |
|                                                                       |
|  [검증] +5 + (-5) = 00000101 + 11111011                              |
|                   = 100000000 (9비트)                                 |
|                   = 00000000 (8비트, 캐리 버림) = 0 ✅                |
|                                                                       |
|  [8비트 범위]                                                         |
|  01111111 = +127 (최대 양수)                                         |
|  00000001 = +1                                                        |
|  00000000 = 0                                                         |
|  11111111 = -1                                                        |
|  10000001 = -127                                                      |
|  10000000 = -128 (최소 음수, 대칭 아님!)                             |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** +5(00000101)를 -5(11111011)로 변환하는 과정을 보여준다. 검증으로 두 수를 더하면 100000000(9비트)이 되고, 8비트 캐리를 버리면 정확히 0이 된다. 이것이 2의 보수의 핵심 — 가산기만으로 뺄셈이 자동으로 성립한다. 주의할 점은 범위가 비대칭이라는 것이다: 양수 최대 +127, 음수 최소 -128. `-(-128) = -128`이 되는 오버플로우가 발생한다.

- **📢 섹션 요약 비유**: 2의 보수는 "시계를 거꾸로 돌리기"입니다. 3시간 빼기 = 9시간 더하기. 뺄셈을 덧셈으로 바꾸니 계산기(ALU)가 하나면 충분합니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 내부 동작 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **MSB (부호 비트)** | 양수/음수 판별 | 0=양수, 1=음수 | 조건 분기(CPU 플래그) | 양수/음수 표지판 |
| **비트 반전 (NOT)** | 1의 보수 생성 | 각 비트 0↔1 교환 | XOR 게이트 | 흑백 반전 사진 |
| **+1 가산** | 2의 보수 완성 | 반전된 값에 1 더함 | 리플 캐리 가산기 | 시계 한 칸 이동 |
| **오버플로우 탐지** | 범위 초과 검출 | MSB 캐리인 ≠ 캐리아웃 | CPU V 플래그 | 시계 한 바퀴 초과 |

### 오버플로우 탐지 원리

```text
+-----------------------------------------------------------------------+
|        오버플로우 탐지 — MSB 캐리 비교                                |
+-----------------------------------------------------------------------+
|                                                                       |
|  [정상] 40 + 50 = 90                                                 |
|    00101000 (+40)                                                     |
|  + 00110010 (+50)     캐리인(C6→C7)=0, 캐리아웃(C7→)=0              |
|  ----------                                                           |
|    01011010 (+90) ✅  C_in = C_out → 오버플로우 없음                 |
|                                                                       |
|  [오버플로우] 100 + 50 = 150 > 127!                                  |
|    01100100 (+100)                                                    |
|  + 00110010 (+50)     캐리인(C6→C7)=1, 캐리아웃(C7→)=0              |
|  ----------                                                           |
|    10010110 (-106?!) ❌ C_in ≠ C_out → 오버플로우 발생!              |
|                                                                       |
|  ★ 양수+양수=음수, 음수+음수=양수 → 오버플로우                      |
|  ★ 양수+음수 → 절대 오버플로우 안 남 (부호가 다르면 안전)           |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 2의 보수 오버플로우는 MSB 위치의 캐리인(C_in)과 캐리아웃(C_out)을 비교하여 탐지한다. 두 값이 다르면 오버플로우이다. CPU의 V(Overflow) 플래그가 이 XOR 결과를 저장한다. 양수+양수가 음수가 되거나, 음수+음수가 양수가 되면 오버플로우이다. 부호가 다른 두 수의 덧셈은 절대 오버플로우가 발생하지 않는다.

- **📢 섹션 요약 비유**: 오버플로우는 "시계가 12를 넘어 다시 1로 돌아가는 것"입니다. 127+1=-128은 시계의 12→1 전환과 같습니다.

## Ⅲ. 비교 및 연결

### 비교 1: 음수 표현 방식 3가지

| 비교 항목 | 부호-크기 | 1의 보수 | 2의 보수 |
|:---|:---|:---|:---|
| **음수 변환** | MSB만 1로 설정 | 비트 전체 반전 | 반전 + 1 |
| **0의 표현** | +0, -0 (2개) | +0, -0 (2개) | **0 하나만** |
| **8비트 범위** | -127 ~ +127 | -127 ~ +127 | **-128 ~ +127** |
| **뺄셈 회로** | 별도 필요 | 가산기 재활용(보정 필요) | **가산기만으로 완전** |
| **현대 사용** | ❌ 미사용 | ❌ 미사용 | ✅ 전 CPU 표준 |

### 과목 융합 관점
- **보안**: 정수 오버플로우 취약점은 2의 보수의 범위 한계에서 발생한다. `INT_MAX + 1 = INT_MIN`이 되어 버퍼 크기 검사를 우회할 수 있다(CVE 다수).
- **네트워크**: TCP/IP 체크섬은 1의 보수 합산을 사용한다(역사적 이유). 2의 보수와 혼동하면 구현 오류.
- **컴파일러**: `-fwrapv`(GCC)는 정수 오버플로우를 2의 보수 래핑으로 정의한다. 없으면 UB(Undefined Behavior).

- **📢 섹션 요약 비유**: 부호-크기는 "양쪽에 문이 있는 방"(+0과 -0), 2의 보수는 "한쪽 문만 있는 원형 방"(0 하나, 끊김 없이 순환)입니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — 정수 오버플로우 보안 취약점**: C 언어에서 `int size = user_input; char *buf = malloc(size + 16);`일 때, `size = INT_MAX`이면 `size + 16`이 음수가 되어 매우 작은 버퍼가 할당되고, 이후 `memcpy`에서 힙 오버플로우가 발생한다. 대응: 연산 전 범위 검사 또는 Safe Integer 라이브러리 사용.

2. **시나리오 — 부호 확장(Sign Extension)**: 8비트 `-5`(11111011)를 32비트로 확장할 때, MSB(1)를 상위 24비트에 복사한다 → 11111111 11111111 11111111 11111011. 0으로 채우면 +251이 되어 값이 완전히 달라진다.

### 안티패턴
- **unsigned와 signed 혼용 비교**: C에서 `if (-1 < 1u)`는 false이다. -1이 unsigned로 변환되면 4294967295(최대값)가 된다.
- **`abs(INT_MIN)` 호출**: `-(-128) = -128`이므로 절대값이 음수가 된다(UB).

- **📢 섹션 요약 비유**: 2의 보수 오버플로우를 모르면 "시계가 12를 넘을 때 1로 돌아가는 걸 모르고, 시간 계산을 하는 것"과 같습니다.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 부호-크기 방식 | 2의 보수 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | 가산기 + 감산기 2개 필요 | 가산기 1개 | 하드웨어 **50%** 절감 |
| **정량** | 0 표현 2개 → 256개 중 255개 유효 | 0 표현 1개 → 256개 전부 유효 | 표현 효율 +1 |
| **정성** | 뺄셈 별도 로직 필요 | 덧셈으로 통합 | 설계 단순화 |

### 참고 표준
- **ISO/IEC 9899:2011 (C11)**: 정수 표현으로 2의 보수 권장 (C23부터 필수)
- **IEEE 1800 (SystemVerilog)**: 하드웨어 기술 언어에서 2의 보수 연산 정의

2의 보수는 "뺄셈을 덧셈으로 바꾸는" 수학적 트릭이자, 현대 디지털 시스템의 정수 연산 기반이다. 범위 비대칭(-128~+127)과 오버플로우 특성을 정확히 이해해야 보안 취약점을 방지할 수 있다.

### 👶 어린이를 위한 3줄 비유 설명

1. 2의 보수는 "시계 거꾸로 돌리기"예요. 3시간 전에 일어난 일을 알려면, 시계를 9시간 앞으로 돌려도 같아요(12-3=9)!
2. 컴퓨터에서 -5를 만들려면: +5의 이진수(00000101)를 뒤집고(11111010) 1을 더하면(11111011) -5가 돼요.
3. 이 방법의 장점은 빼기를 안 해도 돼요! 더하기만으로 빼기까지 할 수 있어서 계산기가 단순해져요.
