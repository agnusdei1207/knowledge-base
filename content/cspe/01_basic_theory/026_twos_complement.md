## 미리 알고가기

- MSB(Most Significant Bit): 비트열의 맨 왼쪽 비트로, 부호 표현 방식에서는 이 비트 하나만 보고 양수인지 음수인지를 먼저 판단하는 기준점 역할을 함
- 부호와 절댓값(Sign-Magnitude) 방식: 맨 앞 비트 하나를 부호 깃발처럼 따로 쓰고 나머지 비트는 그대로 절댓값을 나타내는, 사람이 손으로 쓰는 방식과 가장 비슷한 음수 표현법임
- 1의 보수(One's Complement): 마치 사진의 색을 반전시키듯 모든 비트를 0은 1로, 1은 0으로 뒤집어서 음수를 만드는 방식임
- end-around carry: 1의 보수로 덧셈을 할 때 최상위 자리에서 넘친 캐리를 버리지 않고 다시 최하위 자리로 되돌려 한 번 더 더해주는 보정 절차임
- ALU(Arithmetic Logic Unit): CPU 내부에서 덧셈·뺄셈·논리 연산을 실제로 수행하는 연산 회로임
- 오버플로(Overflow): 정해진 비트 폭으로 표현할 수 있는 범위를 연산 결과가 넘어서 버리는 현상임

## Ⅰ. 개요

- **정의/개념**: 2의 보수(Two's Complement)는 어떤 수의 모든 비트를 반전시킨 뒤 최하위 비트에 1을 더해 그 수의 음수를 만드는 방식으로, 이렇게 만든 음수를 원래 양수와 그대로 더하기만 하면 덧셈 회로 하나로 뺄셈까지 처리할 수 있게 하는 대표적인 정수 부호 표현법임
- **배경/필요성**: 부호와 절댓값 방식은 부호 비트와 절댓값 비트를 따로 처리해야 해서 덧셈 회로와 뺄셈 회로를 별도로 설계해야 하고 $+0$과 $-0$이 서로 다른 비트열로 중복 존재하는 문제가 있음. 1의 보수 방식 역시 end-around carry라는 추가 보정 절차가 필요하고 $+0$과 $-0$ 중복 문제를 그대로 안고 있어, 회로를 단순화하면서 0 표현을 하나로 통일하는 표준 음수 표현 방식이 필요해짐

## Ⅱ. 특징

- ALU(Arithmetic Logic Unit) 단순화: 2의 보수 방식에서는 뺄셈을 "음수를 만들어 더하기"로 바꿔 처리할 수 있어 덧셈 회로 하나만으로 덧셈과 뺄셈을 모두 수행할 수 있고, 그만큼 ALU 내부 회로 구성이 단순해짐
- 0의 유일한 표현: 2의 보수에서는 모든 비트가 0인 경우만 0을 나타내므로 $+0$과 $-0$이 따로 존재하지 않아, 0인지 아닌지를 비교하고 분기하는 제어 로직이 간단해짐
- 고정 비트 폭에 따른 오버플로: 비트 폭 $n$이 고정되어 있어 표현 가능한 범위가 $-2^{n-1}$부터 $2^{n-1}-1$까지로 제한되고, 연산 결과가 이 범위를 벗어나면 오버플로가 발생해 별도의 검출 로직이 필요함
- 부호 유지 산술 시프트: 오른쪽으로 비트를 밀 때 빈 자리를 부호 비트로 채워 넣는 산술 시프트를 쓰면 부호를 그대로 유지한 채 값을 2로 나누는 효과를 낼 수 있어 나눗셈 연산 최적화에 활용됨

## Ⅲ. 종류 및 비교

2의 보수는 정수형 음수 표현의 유일한 방식이 아니며, 부호와 절댓값 방식·1의 보수 방식과 비교했을 때 0 표현 방식과 연산 회로 구조에서 뚜렷한 차이를 보임.

| 판단 기준 | 부호와 절댓값 | 1의 보수 | 2의 보수 |
|:---|:---|:---|:---|
| 0의 표현 개수 | $+0$, $-0$ 2가지로 나뉨 | $+0$, $-0$ 2가지로 나뉨 | 모든 비트가 0인 경우 1가지만 존재함 |
| 덧셈·뺄셈 처리 | 부호 비트와 절댓값을 따로 계산해야 해 회로가 복잡함 | 덧셈 후 end-around carry로 캐리를 다시 더해야 함 | 뺄셈을 덧셈으로 바꿔 처리할 수 있어 회로가 단순함 |
| 하드웨어 채택 여부 | 오늘날 범용 CPU에는 거의 쓰이지 않음 | 오늘날 범용 CPU에는 거의 쓰이지 않음 | 대부분의 현대 CPU가 표준 정수 표현으로 채택함 |

> 요약: 세 방식 모두 음수를 표현하지만, 0 표현이 하나로 통일되고 덧셈 회로만으로 뺄셈까지 처리할 수 있는 2의 보수가 현대 하드웨어의 표준으로 채택됨.

## Ⅳ. 구성요소 및 구조

2의 보수 연산은 Ⅲ에서 확인한 "뺄셈을 덧셈으로 바꿔 회로를 단순화한다"는 판단이 실제 회로에서 어떤 정적 구성요소로 구현되는지를 보여줌.

| 구성요소 | 설명 |
|:---|:---|
| XOR 게이트 배열 (Bit Inverter) | 제어 신호(control)가 뺄셈을 지시하면 $B$의 각 비트를 반전시켜 1의 보수를 만들고, 덧셈을 지시하면 $B$를 그대로 통과시켜 같은 배열 하나로 덧셈·뺄셈 입력을 모두 준비함 |
| $n$비트 가산기 사슬 (Full Adder Chain) | 반전 여부가 결정된 $B$와 $A$를 자리올림(carry)과 함께 더해 결과를 산출하는 회로로, 별도의 뺄셈 회로 없이 이 가산기 하나로 덧셈과 뺄셈을 모두 처리함 |
| 캐리 입력 제어선 (Carry-in Control) | 뺄셈 시 최하위 자리의 캐리 입력을 1로 고정해 1의 보수에 1을 더하는 과정을 가산 동작 안에 흡수시켜 별도의 $+1$ 연산 단계를 없앰 |
| 오버플로 검출 회로 (Overflow Detector) | 최상위 비트로 들어가는 캐리($C_{n-1}$)와 최상위 비트에서 나가는 캐리($C_n$)를 XOR해 두 값이 다르면 오버플로 신호를 발생시켜 고정 비트 폭을 넘는 결과를 표시함 |

```text
        +-----+
  B --->| XOR |---+
 ctrl-->|     |   |
        +-----+   v
                +----------------------+
  A ----------->| n비트 가산기 사슬     |---> 결과(S)
                | (Full Adder Chain)   |
 ctrl(Cin)----->|                      |
                +----------------------+
                    |            |
                 Cn-1           Cn
                    v            v
                  +----------------+
                  |  XOR (오버플로) |---> 오버플로 신호
                  +----------------+
```

> 요약: 뺄셈 전용 회로 대신 XOR 배열과 캐리 입력 제어선이 가산기 사슬 하나를 덧셈·뺄셈에 공용으로 쓰게 하고, 오버플로 검출 회로가 그 결과의 유효 범위를 감시함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+      +------------+      +------------+      +----------+
| 피연산자 | ---> | 2의 보수   | ---> | 캐리 비교  | ---> | 결과 및  |
| 식별     |      | 변환 후 가산|      | (오버플로) |      | 오버플로 |
+----------+      +------------+      +------------+      +----------+
```

1. **피연산자/연산 식별**: $A$, $B$와 연산 종류를 식별하고, 뺄셈이면 제어 신호(control)를 1로 세워 XOR 배열과 캐리 입력 제어선을 뺄셈 모드로 전환함
2. **2의 보수 변환 후 가산**: 뺄셈 모드에서는 $B$를 비트 반전시키고 캐리 입력을 1로 고정해 1의 보수에 1을 더하는 과정을 가산기 사슬 동작 안에서 한 번에 끝내며, 덧셈 모드에서는 $B$를 그대로 더함
3. **캐리 비교(검증)**: 최상위 비트로 들어가는 캐리($C_{n-1}$)와 최상위 비트에서 나가는 캐리($C_n$)를 오버플로 검출 회로에서 비교함
4. **결과 및 오버플로 반환**: 가산 결과와 오버플로 신호를 함께 반환하고, 두 캐리가 다르면 상위 처리 루틴에 오버플로를 통지함

## Ⅵ. 실무 적용 및 유의점

1. 임베디드 제어기나 금융 계산처럼 정수 오버플로가 조용히 랩어라운드(wrap-around)되어 큰 양수가 작은 음수로 뒤바뀌면 안 되는 시스템에서는 컴파일러의 오버플로 검출 옵션이나 포화 연산(saturating arithmetic)을 적용해 대응하고, 오버플로 검출 회로가 발생시키는 신호 빈도와 랩어라운드 발생 건수로 안전성을 확인함
2. 8비트 값을 32비트 레지스터로 옮기는 형변환처럼 서로 다른 비트 폭 데이터를 다루는 저수준 코드에서는 부호 비트를 확장하지 않으면 음수 값이 다른 값으로 왜곡되므로 부호 확장(sign extension) 연산을 명시적으로 적용하고, 형변환 전후 값을 비교하는 테스트로 왜곡 여부를 확인함

## Ⅶ. 결론

2의 보수는 $+0$/$-0$ 중복을 없애고 뺄셈을 가산기 사슬 재사용만으로 처리하게 해 별도의 뺄셈 회로나 end-around carry 없이 오버플로 검출 회로 하나만 더하면 되므로, 현대 CPU 정수 연산의 표준 부호 표현으로 채택됨.
