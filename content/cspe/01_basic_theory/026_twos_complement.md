# 📖 【암기용】 개념 완전 이해

> 목적: 2의 보수와 부호 표현을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 이진수로 양수·음수를 표현하고 산술 연산을 수행하는 방식
- **왜 필요한가**: CPU는 0과 1만 처리하므로 부호, 범위, 오버플로우를 비트 규칙으로 해석해야 한다.
- **핵심 직관**: 2의 보수는 음수를 "모듈러 원형 눈금"의 반대편 값으로 배치해 뺄셈을 덧셈 회로로 처리한다.

## 깊이 이해
- **배경·문제의식**: 부호-크기 방식은 +0과 -0이 생기고, 1의 보수는 end-around carry가 필요하다. 2의 보수는 0을 하나만 갖고 동일 가산기로 덧셈·뺄셈을 처리한다.
- **작동 원리**: n비트 2의 보수 범위는 `-2^(n-1) ~ 2^(n-1)-1`이다. 음수 x는 `2^n - |x|`로 저장되며, 비트 반전 후 1을 더해 얻는다.
- **비유**: 12시간 시계에서 -3시간은 9시와 같다. 8비트에서 -1은 256-1=255, 즉 `11111111`로 표현된다.
- **구체 예시**: 8비트에서 `+5=00000101`, `-5=11111011`; `5+(-5)=00000000`이고 최상위 캐리는 버린다.
- **흔한 오해·주의점**: 캐리 발생과 오버플로우는 다르다. 같은 부호 두 수를 더했는데 결과 부호가 바뀌면 signed overflow이다.

## 연결 개념
- 부동소수점 IEEE 754 — 부호 비트와 지수 bias를 별도 사용
- ALU 가산기 — 2의 보수 덧셈·뺄셈 회로의 기반
- 해밍 코드 — 비트 오류가 수 표현 해석에 미치는 영향


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 2의 보수는 n비트 모듈러 공간에서 음수를 `2^n-|x|`로 매핑하는 정수 부호 표현 방식이다.
> 2. **가치**: 덧셈 회로 1개로 `A+B`, `A-B=A+(~B+1)`을 처리해 ALU 제어를 단순화한다.
> 3. **판단 포인트**: 표현 범위, 0의 유일성, 오버플로우 검출 조건을 부호-크기·1의 보수와 비교해야 한다.


## Ⅰ. 개요 및 필요성

2의 보수는 CPU 정수 산술의 표준 부호 표현이다.  
컴퓨터는 음수 기호를 직접 저장하지 못하므로 최상위 비트와 모듈러 연산으로 부호를 해석한다.  
2의 보수는 `+0/-0` 중복을 제거하고 덧셈기 중심 ALU 설계를 가능하게 한다.


## Ⅱ. 구조 및 구성요소

```text
부호 비트(MSB) -> 크기 비트 -> n비트 모듈러 해석
MSB=1 -> 음수 판단
n-1비트 -> 값 저장
2^n 기준 -> 범위·Overflow 판단
```

| 구성요소 | 역할 | 수치 기준 |
|:---|:---|:---|
| 부호 비트(MSB) | 0이면 양수, 1이면 음수 | n비트 중 1비트 |
| 크기 비트 | 실제 비트 패턴 저장 | n-1비트 |
| 2의 보수 변환 | 음수 `-x`를 `~x+1`로 생성 | 8비트 -5=`11111011` |
| 오버플로우 검출 | 같은 부호 덧셈의 결과 부호 변화 탐지 | `(+)+(+)=(-)`, `(-)+(-)=(+)` |

> 요약: 2의 보수는 MSB 부호 판단, n비트 모듈러 해석, 오버플로우 검출 규칙으로 구성된다.


## Ⅲ. 동작원리 및 흐름도

```text
10진 정수 입력 -> n비트 범위 확인
  / 양수 -> 원형 이진 저장
  / 음수 -> 절댓값 이진화 -> 비트 반전 -> +1 -> 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | n비트 표현 범위 확인 | `-2^(n-1) ~ 2^(n-1)-1` |
| 2 | 양수는 일반 이진수로 저장 | 8비트 +5=`00000101` |
| 3 | 음수는 비트 반전 후 1 더함 | 8비트 -5=`11111011` |
| 4 | 연산 후 최상위 캐리 폐기, 부호 검사 | signed overflow 조건 확인 |

> 요약: 음수는 `절댓값 -> 반전 -> +1`로 만들고, 산술 결과는 n비트 범위와 부호 변화로 검증한다.


## Ⅳ. 특징

| 구분 | 부호-크기/1의 보수 | 2의 보수 | 판단 포인트 |
|:---|:---|:---|:---|
| 0 표현 | +0, -0 2개 가능 | 0 표현 1개 | 비교 연산 단순화 |
| 표현 범위(8비트) | -127~+127 | -128~+127 | 음수 1개 추가 |
| 뺄셈 처리 | 별도 보정 또는 차감 회로 | `A+(~B+1)` | 가산기 재사용 |
| 오버플로우 | 표현 방식별 별도 판단 | 같은 부호 덧셈 결과 부호 변화 | ALU flag 설계 |

> 요약: 2의 보수는 0 중복 제거와 가산기 재사용이 핵심이며, signed overflow는 캐리와 분리해 판단한다.


## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 표현 | 부호-크기·1의 보수 | 2의 보수 | 0 표현 1개와 가산기 재사용 필요 |
| 비용/성능 | 별도 뺄셈 회로 | `A+(~B+1)` | ALU 면적·제어 단순화 |
| 운영/위험 | overflow 미점검 | signed overflow flag | 안전 언어·포화 산술 적용 여부 |

> 요약: 2의 보수는 CPU 정수 산술의 기본 선택이나, overflow 정책을 자료형별로 명시해야 함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| signed overflow | 범위 `-2^(n-1)~2^(n-1)-1` 초과 | 64비트 승격, checked arithmetic | overflow trap 건수 |
| 부호 혼동 | signed/unsigned 혼합 비교 | 정적 분석, 타입 명시 | compiler warning 0건 |
| 프로토콜 오해 | 비트 폭 누락 | 필드별 signed·폭 문서화 | 상호운용 테스트 통과율 |

> 요약: 정수 오류는 overflow, 부호 혼동, 비트 폭 누락에서 발생하므로 타입과 검증 패턴으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 범위 검증 | 경계값 -128, -1, 0, 127 통과 | 단위 테스트 |
| ALU flag | C/V/N/Z flag 기대값 일치 | RTL 시뮬레이션 |
| 정적 품질 | signed/unsigned warning 0건 | 컴파일러·lint |

> 요약: 2의 보수 적용 품질은 경계값 테스트, flag 검증, 정적 분석으로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 임베디드 C 정수 설계: `int8_t` 범위 -128~127, 센서 오프셋 계산 시 signed overflow 테스트 케이스 포함
2. ALU 검증: `0x7F+0x01=0x80`, `0x80+0xFF=0x7F` 패턴으로 V flag 검증
3. 프로토콜 설계: 네트워크 필드에 signed/unsigned와 비트 폭(예: 16비트 signed)을 명시

**결론 (2줄):**
- 기술사 판단: CPU 정수 연산은 2의 보수를 기본으로 하되, 범위 초과 가능성이 있으면 32비트에서 64비트 승격 또는 포화 산술을 선택함
- 향후 방향: 안전 언어(Rust, Swift)는 debug overflow trap, release wrapping 등 실행 모드를 명시해 정수 오류를 통제함
