# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 2의 보수(Two's Complement)는 **정수의 음수**를 2진수로 표현하는 방식으로, 모든 비트를 반전(1의 보수)한 뒤 1을 더해 음수를 만들며, 현대 컴퓨터 **ALU의 데팩토 표준**이다.
- **왜 필요한가**: 컴퓨터에 뺄셈기(Subtractor)를 따로 만들지 않고, **덧셈기(Adder) 하나만으로** A - B = A + (-B)를 처리해 하드웨어를 단순화하기 위해서다.
- **핵심 직관**: 자동차 주행거리계(9999)에서 1km를 뒤로 가면 9998이 되듯, 4비트 0000에서 1을 빼면 자리내림(Borrow)이 발생해 1111(-1)이 된다 — 모듈러 산술(mod 2^N)의 원리이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

2의 보수 체계와 선행 음수 표현 방식을 비교하며 세운다. 부동소수점의 부호 비트(025)와 다른 방식임에 주의.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 모듈러 산술 (상위 키워드) | 2^N을 법(Modulus)으로 하는 순환 연산 체계 | 시계: 12시 다음이 다시 1시 |
| 부호화 절대치 (Sign-Magnitude) | 최상위 1비트를 부호(0=+, 1=-)로 쓰고 나머지가 크기 | 1001₂ = -1, 0001₂ = +1 |
| 1의 보수 (1's Complement) | 모든 비트를 반전해 음수를 표현 | 0001(+1) → 1110(-1) |
| 2의 보수 (2's Complement) | 1의 보수에 1을 더해 음수를 표현 — 2^N - N과 동일 | 0001(+1) → 1110+1 = 1111(-1) |
| 오버플로우 (Overflow) | 연산 결과가 N비트 표현 범위를 초과해 부호가 반전되는 오류 | 0111(+7) + 0001(+1) = 1000(-8) |
| MSB (최상위 비트) | 2의 보수에서 부호를 나타내는 최상위 비트 (0=양수, 1=음수) | 숫자의 부호 판단 기준 |
| 부호 확장 (Sign Extension) | 비트 수를 늘릴 때 MSB 값을 상위 비트에 복사해 값 보존 | 4비트 1101(-3) → 8비트 11111101(-3) |

## 깊이 이해
- **배경·문제의식**:
  - **부호화 절대치**: +0(0000)과 -0(1000) 두 개가 존재하며, 뺄셈을 위해 별도 감산기가 필요하다.
  - **1의 보수**: 역시 +0(0000)과 -0(1111) 두 개가 존재하고, 자리올림(End-around Carry) 발생 시 끝에 1을 다시 더해야 하는 추가 회로가 필요하다.
  - **2의 보수**는 이 두 문제를 모두 해결한다.
- **작동 원리**:
  - **변환**: N의 2의 보수 = 2^n - N = (비트 반전) + 1. 예: 4비트에서 3(0011)의 2의 보수 = 1100 + 1 = 1101(-3).
  - **0의 유일성**: +0(0000)의 2의 보수는 1111 + 1 = 10000이나, 4비트만 남기면 0000이 되어 0이 하나뿐이다.
  - **뺄셈 = 덧셈**: 5 - 3 → 0101 + 1101 = 10010. 5비트 째 캐리를 버리면 0010(2)이 정확히 나온다. 별도 감산기가 불필요하다.
  - **표현 범위**: N비트에서 -2^(N-1) ~ 2^(N-1)-1. 8비트: -128 ~ +127. 음수가 양수보다 1개 더 많다(-128의 양수 대응값이 없음).
- **비유**: 시계에서 3시간 전으로 돌아가려면 뒤로 3칸 돌려도 되지만, 앞으로 9칸(12-3=9) 돌려도 같은 자리다. 2의 보수는 "뒤로 빼는 대신 앞으로 한 바퀴 돌려 맞추는" 모듈러 산술이다.
- **구체 예시 (8비트)**: -50 표현 — ① 50 = 00110010₂, ② 비트 반전 = 11001101, ③ +1 = 11001110₂ = -50. 검증: 00110010 + 11001110 = 100000000 → 캐리 버리면 00000000(0) ✓
- **흔한 오해·주의점**:
  - **"2의 보수 = 음수"가 아니다**: 2의 보수는 체계(system) 전체를 말하며, MSB가 0인 수(0101)는 그냥 양수이고, 양수에 보수 연산을 취해야 음수가 된다.
  - **부동소수점과 혼동**: IEEE 754(025)는 부호 비트를 분리하는 Sign-Magnitude 방식이며, 2의 보수를 사용하지 않는다.
  - **-128의 특이성**: 8비트에서 -128(10000000)의 2의 보수를 취하면 다시 -128이 된다. abs(INT_MIN)은 정의되지 않으므로 한 단계 큰 자료형으로 승격해야 한다.

## 연결 개념
- **수 체계 변환 (024)**: 2진수 변환 기초 — 2의 보수는 이 위에 음수 표현을 추가한다.
- **부동소수점 IEEE 754 (025)**: 실수의 부호 표현(Sign-Magnitude)과 대비되는 정수의 부호 표현.
- **조합 논리 회로 (028)**: 전가산기(Full Adder)가 2의 보수 덧셈을 물리적으로 구현하는 회로.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 2의 보수는 2^N 모듈러 산술 기반으로 비트 반전+1로 음수를 표현하며, 0을 하나로 통일하고 뺄셈을 덧셈으로 치환하는 정수 표현의 데팩토 표준임.
> 2. **가치**: 감산기를 별도로 만들지 않고 전가산기의 Cin=1 설정만으로 가감산을 통합해 ALU 하드웨어를 단순화함.
> 3. **판단 포인트**: 표현 범위 비대칭(-2^(N-1) ~ 2^(N-1)-1)과 MSB 캐리 불일치(Cin ⊕ Cout = 1)에 의한 오버플로우 검출 메커니즘이 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 음수 표현 방식의 발전 과정 | 부호화 절대치→1의 보수→2의 보수, 0 개수 차이 | 각 방식의 0 표현(+0, -0) 차이 누락 |
| 2의 보수의 하드웨어 이점 | 감산기 불필요, 가산기 Cin=1 통합, 캐리 무시 원리 | 1의 보수의 순환 캐리 가산과 혼동 |
| 오버플로우 검출 메커니즘 | Cin ⊕ Cout = 1 판별식, OF 플래그 세팅 | "범위를 넘는다"고만 추상적 서술 |

> 요약: 다른 음수 표현 대비 2의 보수의 유일한 0과 가산기 재사용 이점을 부각하고, 오버플로우 검출 회로 로직까지 도달해야 함.

## Ⅰ. 개요 및 필요성
- 개요: 2^N 모듈러 연산 기반으로 비트 반전(NOT)+1로 음수를 표현하는 정수 부호 표현 체계임
- 배경: 부호화 절대치·1의 보수는 0이 두 개 존재하고 감산 회로가 별도로 필요해 하드웨어 비용이 높음
- 필요성: 음수 처리를 양수 덧셈과 동일한 회로(전가산기)로 통합해 ALU를 단순화하고 연산 사이클을 단축함

## Ⅱ. 구조 및 구성요소
선형 구조도 (2의 보수 기반 가감산 회로):

    [B 입력] -> NOT 게이트(비트 반전) -> [+1 (Cin=1)] -> [2의 보수 -B]
                                                            |
    [A 입력] ------------------------------------------------> [전가산기(FA)] -> [결과 A+(-B)]

| 구성요소 | 연산 메커니즘 | 하드웨어 구현 |
|:---|:---|:---|
| 비트 반전 (1의 보수) | 모든 비트 x를 1-x로 반전 | NOT 게이트 어레이 |
| +1 가산 (2의 보수 완성) | 1의 보수에 LSB 1을 가산 | 가산기의 Cin 핀에 1 입력 |
| 가감산 통합 | A - B = A + (NOT B + 1) | N-bit 전가산기 1개로 덧셈·뺄셈 겸용 |

> 요약: 별도 감산기 없이 전가산기의 입력단 NOT 반전 + Cin=1만으로 감산을 구현함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (2의 보수 가감산 및 오버플로우 판별):

    A, B 입력 -> [S=0: 가산, S=1: B반전+Cin=1] -> N-bit 전가산기 -> 결과 산출 -> Cin ⊕ Cout 판별 -> 정상/오버플로우

1. 부호·변환: 제어 신호가 감산(S=1)이면 감수 B의 비트를 모두 반전하고 Cin을 1로 세팅해 2의 보수(-B)를 생성함
2. 가산 수행: A와 -B(또는 가산 시 B)를 N-bit 전가산기로 통과시켜 합(Sum)과 최종 Cout을 산출함
3. 캐리 처리: MSB에서 발생한 Cout은 2의 보수 체계에서 무시(Discard)하면 정확한 결과가 보장됨
4. 오버플로우 검증: MSB의 Cin과 Cout을 XOR한 결과가 1이면 오버플로우 플래그(OF)를 세팅하고 소프트웨어 예외를 발생시킴

> 요약: 초과 캐리를 버려도 결과가 정확한 것이 2의 보수의 핵심 이점이며, Cin ⊕ Cout으로 오버플로우를 하드웨어 수준에서 검출함.

## Ⅳ. 특징
- 유일한 0: +0의 2의 보수가 자기 자신(0000)이 되어 -0이 존재하지 않으므로 비교 연산이 명확함
- 비대칭 표현 범위: N비트에서 -2^(N-1) ~ 2^(N-1)-1로 음수가 양수보다 1개 더 많음 (8비트: -128 ~ +127)
- 부호 확장 용이: 비트 수 확장 시 MSB(부호 비트) 값을 상위 비트에 복사하면 값이 보존됨 (4비트 1101(-3) → 8비트 11111101(-3))
- 가감산 회로 통합: 전가산기 1개로 덧셈·뺄셈을 모두 처리해 ALU 칩 면적을 절약함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 부호화 절대치 | 1의 보수 | 2의 보수 |
|:---|:---|:---|:---|
| 0 표현 | 2개 (+0, -0) | 2개 (+0, -0) | 1개 (0000만) |
| 뺄셈 회로 | 감산기 별도 필요 | 캐리 발생 시 +1 추가 필요 | 전가산기 하나로 통합 (캐리 버림) |
| 8비트 표현 범위 | -127 ~ +127 | -127 ~ +127 | -128 ~ +127 |
| 실무 채택 | IEEE 754 부동소수점 부호 비트 | 역사적 (현재 미사용) | 정수 연산 ALU 데팩토 표준 |

> 요약: 부호화 절대치·1의 보수는 0 중복과 회로 복잡도로 도태되었으며, 2의 보수가 유일한 0과 가산기 통합 이점으로 표준이 됨.

**리스크·대응:**
- 오버플로우 오류: 양수+양수=음수(0111+0001=1000) 같은 범위 초과 발생 → Cin ⊕ Cout XOR 게이트로 OF 플래그 자동 세팅, 소프트웨어 예외 처리 (지표: 캐리 불일치 시 1)
- -128(INT_MIN) 예외: abs(-128)이 8비트로 표현 불가(보수 취해도 -128) → 컴파일러가 abs(INT_MIN) 시 한 단계 큰 자료형으로 자동 승격 (지표: abs(INT_MIN) 오류율 0%)

**점검 지표:**
- 오버플로우 검출: ALU OF 플래그 정확 동작 — 테스트 벡터(경계값 ±2^(N-1)-1) 검증
- 정수 연산 정확성: 부호 확장·절삭 시 값 보존 여부 — 크로스 플랫폼 비교 테스트

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. ALU 가감산기 통합 설계: MUX와 NOT 게이트를 결합한 가/감산 통합 회로로 칩 면적(Die Area)을 절약하고 제어 신호 1개(S)로 가감산을 전환함
2. 컴파일러 비트 연산 최적화: x × 7을 (x << 3) - x로 치환하고, 감산을 2의 보수 덧셈 (x << 3) + (~x + 1)로 매핑해 곱셈기 없이 명령어 사이클을 단축함
3. 시큐어 코딩 오버플로우 방어: C/C++에서 a + b 전에 if (a > INT_MAX - b) 사전 검증으로 2의 보수 오버플로우로 인한 정수 오버플로우 취약점(CWE-190)을 차단함

**결론:**
- 기술사 판단: 2의 보수는 모듈러 산술로 뺄셈을 덧셈에 통합해 ALU 하드웨어를 단순화한 핵심 설계 원리이며, 모든 정수 연산 아키텍처의 근간임
- 향후 방향: 하드웨어 설계는 2의 보수로 완성되었으나, 소프트웨어 레벨의 정수 오버플로우 취약점이 지속되어 Rust처럼 컴파일러·런타임 단의 바운더리 체크가 의무화되는 추세임
