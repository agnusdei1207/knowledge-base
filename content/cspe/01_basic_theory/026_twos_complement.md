## 미리 알고가기

- 부호 비트: 고정 비트폭에서 최상위 비트(MSB)로 양수와 음수를 구분하는 비트임
- 부호-크기 표현: MSB는 부호, 나머지는 절댓값 크기를 나타내는 방식임
- 1의 보수: 모든 비트를 반전해 음수를 표현하는 방식임
- 2의 보수: 비트 반전 후 1을 더해 음수를 표현하는 방식임
- 오버플로우: 고정 비트폭으로 표현 가능한 범위를 넘어 연산 결과가 왜곡되는 현상임

## Ⅰ. 개요

- **정의**: 2의 보수는 고정 비트폭 이진수에서 음수를 `비트 반전 + 1` 기준으로 표현하는 방식이며, 덧셈 회로 하나로 양수 덧셈과 음수 뺄셈을 동일하게 처리하기 위해 사용함.
- **배경/필요성**: 부호-크기와 1의 보수는 +0/-0 중복 표현과 별도 뺄셈 처리 문제가 있으므로, CPU 산술 논리를 단순화하고 0을 하나로 표현하는 체계가 필요함.
- **비유**: 12시간 시계에서 3시간을 빼는 대신 9시간을 더해 같은 위치에 도달하는 순환 계산 방식과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 음수 이진 표현 원리 설명 | 부호-크기, 1의 보수, 2의 보수 비교 | 단순 반전으로만 설명 |
| 산술 회로 관점 이해 | 단일 가산기, 범위, 오버플로우 판정 | carry와 overflow 혼동 |

> 요약: 2의 보수는 고정 비트폭에서 음수를 순환 덧셈으로 표현해 산술 회로를 단순화하는 표준 정수 표현 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 부호-크기/1의 보수 | 2의 보수 |
|:---|:---|:---|
| 0 표현 | +0과 -0이 모두 존재할 수 있음 | 0이 하나만 존재함 |
| 가감산 회로 | 부호 처리와 뺄셈 보정 로직이 필요함 | 덧셈 회로로 뺄셈까지 처리함 |
| 표현 범위 | 양수와 음수 범위가 대칭에 가까움 | n비트에서 `-2^(n-1)`부터 `2^(n-1)-1`까지 표현함 |
| 선택 기준 | 사람이 부호와 크기를 직관적으로 보기 쉬움 | CPU 정수 산술과 메모리 표현에 적합함 |

- **연산 기준**: 음수를 더하는 방식으로 뺄셈을 처리하므로 ALU 설계가 단순해짐.
- **범위 기준**: 음수 최솟값의 절댓값이 양수 최댓값보다 1 크다는 비대칭을 반드시 고려함.
- **판정 기준**: 최상위 비트로 부호를 판단하되, 오버플로우는 입력 부호와 결과 부호의 관계로 판단함.

> 요약: 2의 보수는 표현 범위가 비대칭인 대신 0 중복을 제거하고 정수 가감산을 같은 하드웨어 흐름으로 통합함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Positive   | ---> | Bit        | ---> | Add One    |
| Magnitude  |      | Inversion  |      | Negative   |
+------------+      +------------+      +------------+
       |                   |                   |
       v                   v                   v
+------------+      +------------+      +------------+
| Sign Bit   |      | Fixed      |      | Overflow   |
| MSB        |      | Width      |      | Check      |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 고정 비트폭 | n비트 범위 안에서 모든 값이 순환적으로 표현되는 전제 조건임 | 정해진 칸 수의 계기판 |
| 부호 비트 | 최상위 비트가 0이면 비음수, 1이면 음수로 해석하는 기준임 | 방향 표지 |
| 비트 반전 | 양수의 각 비트를 0은 1로, 1은 0으로 바꾸어 1의 보수를 만듦 | 색 반전 |
| 1 더하기 | 1의 보수에 1을 더해 2의 보수 음수 표현을 완성함 | 한 칸 밀어 보정 |
| 오버플로우 판정 | 같은 부호 피연산자의 결과 부호가 달라질 때 범위 초과를 판단함 | 계기판 범위 초과 경고 |

> 요약: 2의 보수는 고정 비트폭, 부호 비트, 반전, 1 더하기, 오버플로우 판정이 함께 작동해 음수와 산술 연산을 처리함.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Fix Width  | ---> | Invert     | ---> | Add One    | ---> | Operate    |
| n bits     |      | Bits       |      | Mod 2^n    |      | and Check  |
+------------+      +------------+      +------------+      +------------+
```

1. **비트폭 확정**: 4비트, 8비트, 32비트처럼 해석할 고정 길이를 먼저 정함.
2. **음수 변환**: 양수 절댓값을 n비트로 표현하고 모든 비트를 반전한 뒤 1을 더함.
3. **산술 연산**: 덧셈은 일반 이진 덧셈으로 수행하고 n비트를 넘는 carry는 버림.
4. **범위 검증**: 결과 부호와 입력 부호를 비교해 오버플로우 여부를 판단함.

> 요약: 2의 보수 계산은 비트폭을 고정한 뒤 반전+1로 음수를 만들고, 모듈러 덧셈 후 오버플로우를 확인하는 절차임.

## Ⅴ. 문제점

- **P1 범위 비대칭**: `-2^(n-1)`은 양수 대응값이 없어 절댓값 변환이나 부호 반전에서 예외가 발생함.
- **P2 오버플로우 오판**: 최종 carry만 보고 overflow를 판단하면 signed 정수 범위 초과를 놓칠 수 있음.
- **P3 비트폭 의존성**: 같은 비트열도 8비트인지 16비트인지, signed인지 unsigned인지에 따라 전혀 다른 값이 됨.

> 요약: 2의 보수 해석은 최솟값 예외, overflow 판정 기준, 비트폭·부호 조건을 놓칠 때 오류가 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 최솟값 부호 반전은 별도 예외로 처리하고 포화 연산 또는 더 넓은 자료형을 사용함. (확인: `INT_MIN` 테스트)
- **P2 대응**: 같은 부호 입력의 결과 부호 변화 또는 carry-in/carry-out 차이로 overflow를 판정함. (확인: signed overflow 케이스)
- **P3 대응**: 모든 비트열 표기에 비트폭과 signed/unsigned 해석을 명시하고 sign extension 규칙을 적용함. (확인: 형 변환 테스트)

> 요약: 2의 보수는 비트폭과 signed 해석을 명시하고 최솟값과 overflow를 별도 테스트해야 안전하게 사용할 수 있음.

## Ⅶ. 전망

- **발전 방향**: 범용 CPU, GPU, 임베디드 MCU의 signed 정수 표현은 계속 2의 보수를 기본으로 유지할 전망임.
- **기술사적 판단**: 저수준 디버깅, 프로토콜 필드, 보안 취약점 분석에서는 비트폭과 overflow 조건을 먼저 확인해야 함.
- **기술사 제언**: 답안에서는 부호 표현 비교와 ALU 단순화 효과, overflow 판정 기준을 함께 제시해야 함.
