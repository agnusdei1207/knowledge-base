## 핵심 답안

트리 구조는 노드와 간선의 부모-자식 관계로 계층과 정렬 관계를 표현하는 비선형 자료구조이며, 탐색·삽입·삭제 성능은 트리 높이와 균형 유지 방식에 의해 결정됨.

```text
Root -> Key 비교 -> Child 선택 -> Leaf/Target 도달 -> 필요 시 균형 복구
```

기술사 답안에서는 트리를 계층 표현으로만 설명하지 말고, **높이**, **균형**, **범위 질의**, **저장 매체(메모리/디스크)** 기준으로 B-Tree, AVL, Red-Black Tree를 비교해야 함.

## 트리 계열 비교

| 구분 | B-Tree | AVL Tree | Red-Black Tree |
|:---|:---|:---|:---|
| 구조 | 노드 하나에 여러 키와 자식 저장 | 좌우 높이 차를 엄격히 제한 | 색상 규칙으로 완화된 균형 유지 |
| 목표 | 디스크·페이지 접근 최소화 | 탐색 경로 최소화 | 갱신 비용과 균형의 절충 |
| 탐색 | `O(log_m n)` | `O(log n)` | `O(log n)` |
| 갱신 | 분할·병합 | 회전이 비교적 잦음 | 회전이 상대적으로 적음 |
| 대표 활용 | DB 인덱스, 파일시스템 | 조회 중심 메모리 구조 | 범용 map/set |

B-Tree는 이진 트리가 아니라 다진 검색 트리이며, 한 노드가 저장장치 페이지와 잘 맞도록 여러 키를 담아 트리 높이와 I/O 횟수를 줄임.

## 선택 기준

| 요구사항 | 적합한 판단 |
|:---|:---|
| 정렬된 순회와 범위 검색 필요 | 트리 계열이 해시보다 유리함 |
| 디스크 기반 대용량 인덱스 | B-Tree 또는 B+Tree 우선 검토 |
| 메모리 내부 조회가 많음 | AVL Tree로 짧은 탐색 경로 확보 |
| 삽입·삭제가 자주 발생 | Red-Black Tree로 갱신 비용 완화 |
| 동등 검색만 중요 | 해시 테이블과 비교 필요 |

트리 선택은 "로그 시간"만으로 끝나지 않고, 읽기/쓰기 비율, 범위 질의, 저장 매체 접근 단위를 함께 판단해야 함.

## 핵심 구성요소

| 구성요소 | 의미 | 품질 영향 |
|:---|:---|:---|
| 루트 | 탐색 시작점 | 높이와 접근 경로의 시작 |
| 키 | 비교와 분기 기준 | 정렬 불변식 유지 |
| 자식 포인터 | 하위 노드로 이동 | 탐색 경로 결정 |
| 리프 | 끝 노드 또는 실제 데이터 접근 지점 | 범위 순회·데이터 접근 방식 |
| 균형 정보 | 높이, 색상, 키 개수 등 | 최악 탐색 시간 보장 |

균형 정보가 잘못 갱신되면 정렬 검색은 당장 되는 것처럼 보여도 장기적으로 높이가 증가해 `O(n)` 경로가 생길 수 있음.

## 운영 리스크와 대응

| 리스크 | 원인 | 대응 |
|:---|:---|:---|
| 편향 트리 | 정렬된 입력을 일반 BST에 삽입 | AVL/RB/B-Tree 등 균형 트리 사용 |
| 갱신 비용 증가 | 회전, 색상 변경, 분할·병합 반복 | 조회/갱신 비율로 트리 선택 |
| 저장 매체 불일치 | 디스크 인덱스에 이진 트리식 접근 | 페이지 단위 B/B+Tree 설계 |
| 동시 갱신 충돌 | 같은 노드·경로를 여러 작업이 변경 | latch coupling, MVCC, copy-on-write |
| 구현 복잡성 | 삭제와 재균형 규칙 누락 | 검증된 라이브러리와 불변식 테스트 |

트리는 최악 성능 보장을 위해 메타데이터와 구조 변경 비용을 감수하는 자료구조임.

## 오해와 감점 포인트

- **B-Tree와 Binary Tree 혼동**: B-Tree는 다진 균형 검색 트리임
- **균형 필요성 누락**: 일반 BST는 입력 순서에 따라 `O(n)`까지 나빠질 수 있음
- **AVL/RB 차이 단순화**: AVL은 탐색, RB는 갱신 균형에 상대적으로 유리함
- **저장 매체 누락**: DB 인덱스에서는 CPU 비교보다 페이지 I/O가 더 중요할 수 있음
- **해시와 비교 누락**: 동등 검색만 필요하면 트리가 항상 최선은 아님

## 답안 작성 포인트

1. 정의는 "계층과 정렬 관계를 노드·간선으로 표현하는 비선형 자료구조"로 씀
2. 높이가 탐색 비용을 좌우하므로 균형 유지 필요성을 설명함
3. B-Tree, AVL, RB를 구조·갱신·적용 환경 기준으로 비교함
4. 범위 질의와 정렬 순회가 해시 대비 강점임을 언급함
5. 결론은 "트리 선택은 저장 매체와 조회/갱신 비율에 맞춰야 한다"로 마무리함

> 기술사 관점에서 트리 구조는 로그 시간 탐색의 암기 대상이 아니라, 범위 질의와 최악 성능 보장을 위해 높이를 통제하는 인덱스 설계 도구임.
