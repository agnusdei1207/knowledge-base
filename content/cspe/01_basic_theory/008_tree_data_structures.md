# 008. 트리 구조 — B-Tree·AVL·Red-Black (Tree Data Structures) [출제:122,137회]

## Ⅰ. 개요

- **정의/개념**: 트리는 부모-자식 관계로 계층을 형성하는 비선형 자료구조이며, 검색 트리는 "왼쪽 < 부모 < 오른쪽" 정렬 불변식을 유지해 매 단계 탐색 후보를 절반으로 축소하는 자료구조다.
- **배경/필요성**: 배열은 중간 삽입·삭제 비용이 크고 해시는 정렬·범위 검색을 지원하지 못하는데, 검색 트리는 키를 정렬 상태로 유지해 이 한계를 보완한다. 다만 편향이 발생하면 탐색 성능이 `O(n)`으로 저하되므로 균형 유지 기법이 요구된다.

## Ⅱ. 특징 및 비교

세 구조 모두 최악의 경우에도 높이를 `O(log n)`으로 제한하지만, 균형 유지 강도와 대상 저장 매체에서 차별화된다.

| 구분 | AVL(Adelson-Velsky and Landis) Tree | Red-Black Tree | B-Tree |
|:---|:---|:---|:---|
| 균형 방식 | 좌우 높이차 ≤ 1 (엄격) | 색상 규칙 (완화) | 노드당 다중 키 (다진 구조) |
| 갱신 비용 | 회전 빈도 높음 | 회전 빈도 낮음 | 노드 분할·병합 |
| 강점 | 조회 성능 최적 | 조회·갱신 균형 | 디스크 I/O 최소화 |
| 적용 영역 | 조회 위주 메모리 구조 | 범용 map/set | DB·파일시스템 인덱스 |

> 요약: 조회 위주는 AVL, 갱신이 혼재하면 Red-Black, 디스크 저장은 B-Tree가 유리하다.

AVL Tree는 균형 조건을 가장 엄격히 강제해 조회 성능이 우수한 대신 갱신마다 회전 연산이 빈번하며, Red-Black Tree는 색상 규칙으로 균형 조건을 완화해 회전 빈도를 낮춤으로써 범용 컨테이너의 기본 구현으로 채택된다. B-Tree는 노드 하나에 다수의 키를 저장해 트리 높이를 낮춤으로써, 블록 단위로 접근하는 디스크 환경에서 I/O 횟수를 최소화한다.

## Ⅲ. 구성요소/구조

```text
        [50]
       /    \
    [30]    [70]        좌측 서브트리 < 부모 < 우측 서브트리
    /  \    /  \
 [20][40][60][80]       리프: 값의 종단이자 범위 순회의 지점
```

탐색은 루트에서 시작해 키 비교 결과에 따라 한쪽 서브트리로만 진행하므로, 단계마다 탐색 후보가 절반으로 감소한다.

- **루트·키**: 탐색의 출발점이자 "좌측 < 부모 < 우측" 정렬 불변식의 판단 기준
- **자식 포인터**: 비교 결과에 따라 한쪽 가지로만 분기하는 연결 구조
- **균형 정보**: 높이차·색상·키 개수로 편향을 제어해 높이를 제한
- **리프**: 값의 종단 노드이며 범위 검색 시 순회의 경유 지점

트리 성능은 루트에서 리프까지의 높이에 의해 결정되며, 세 구조가 서로 다른 방식으로 추구하는 목표는 결국 높이를 `O(log n)`으로 제한하는 것으로 수렴한다.

## Ⅳ. 문제점 및 개선방안

1. **편향 트리**: 균형 규칙이 없는 이진 탐색 트리에 정렬된 키가 순서대로 삽입되면 한쪽으로 치우쳐 탐색 비용이 `O(n)`까지 악화된다.
   - **개선방안**: 삽입·삭제마다 균형을 재조정하는 AVL·Red-Black·B-Tree를 적용한다. (확인: 최악 높이 `O(log n)` 유지 여부)
2. **균형 유지 비용**: 회전·분할·병합 연산이 갱신마다 수반되어 갱신 빈도가 높을수록 부하가 누적된다.
   - **개선방안**: 조회 위주 워크로드에는 AVL, 조회·갱신 혼재 워크로드에는 Red-Black을 적용해 비율에 맞춘다. (확인: 조회·갱신 지연 분포)
3. **저장 매체 불일치**: 디스크 인덱스에 이진 트리를 적용하면 노드 접근마다 디스크 I/O가 발생해 높이만큼 반복된다.
   - **개선방안**: 디스크·DB 인덱스에는 높이가 낮은 B-Tree/B+Tree를 적용한다. (확인: 질의당 디스크 읽기 횟수)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터베이스 인덱스 | B+Tree로 정렬 출력과 범위 질의를 지원 | 트리 높이, 페이지 읽기 수 |
| 프로그래밍 언어·커널 map/set | Red-Black Tree로 정렬 순회와 로그 시간 갱신을 제공 | 조회·삽입 지연 |
| 파일시스템 | B-Tree 계열로 메타데이터·블록 위치를 관리 | 디스크 I/O 횟수 |

> 요약: 정렬·범위 검색은 검색 트리, 디스크 환경은 B-Tree 계열, 메모리 범용 구조는 Red-Black Tree가 적합하다.

## Ⅵ. 결론

검색 트리는 배열과 해시가 제공하지 못하는 정렬·범위 검색을 로그 시간에 지원하지만, 균형이 붕괴되면 이 이점이 상실된다. 따라서 선택은 워크로드의 조회·갱신 비율과 저장 매체(메모리·디스크)를 기준으로 AVL·Red-Black·B-Tree 중 적합한 균형 트리를 판단하는 문제로 귀결된다.
