# 📖 【암기용】 개념 완전 이해

> 목적: 트리를 계층 구조 표현, 탐색 비용, 균형 유지 원리 관점에서 이해하게 만든다.

## 한눈에
- **개요**: 루트에서 자식으로 뻗는 계층형 비선형 자료구조
- **왜 필요한가**: 정렬된 데이터 탐색, 파일 시스템, DB 인덱스처럼 계층·범위 탐색을 O(log n) 수준으로 처리해야 함
- **핵심 직관**: 데이터를 줄로 세우지 않고 질문을 반씩 줄이는 결정 나무로 배치하는 구조임

## 깊이 이해
- **배경·문제의식**: 리스트는 탐색 O(n), 정렬 배열은 삽입 O(n)이다. 균형 트리는 탐색·삽입·삭제를 높이 h에 비례시키고 h를 log n으로 제한함
- **작동 원리**: BST는 왼쪽<루트<오른쪽 규칙을 사용함. AVL은 높이 차를 |h(left)-h(right)| ≤ 1로 유지하고, Red-Black은 색 규칙과 회전으로 균형을 유지하되 삽입·삭제 시 회전을 최대 2~3회로 억제함. B-Tree는 한 노드에 여러 키를 저장해 디스크 I/O를 줄임
- **비유**: 도서관 서가를 층-구역-책장 순서로 나누면 한 권을 찾을 때 전체를 훑지 않고 범위를 계속 좁힐 수 있음
- **구체 예시**: 1,000,000개 키에서 균형 이진트리 높이는 약 log2(1,000,000)=20, B-Tree fanout 100이면 높이는 약 3단계임
- **흔한 오해·주의점**: 이진 탐색 트리가 항상 O(log n)은 아님. 정렬 입력이 그대로 들어오면 한쪽으로 치우쳐 높이 n이 될 수 있음

## 연결 개념
- 이진 탐색 — 배열 기반 반분 탐색 비교 / B+Tree — DBMS 범위 검색 / 힙 — 완전 이진트리 기반 우선순위 큐

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 트리는 루트·간선·자식 관계로 계층과 탐색 공간 분할을 표현하는 비선형 자료구조이다.
> 2. **가치**: 균형 유지 시 탐색·삽입·삭제를 O(log n)으로 제한하고, B-Tree는 디스크 I/O 횟수를 높이 수준으로 제한한다.
> 3. **판단 포인트**: 메모리 내 정렬 집합은 AVL/Red-Black, DB·파일시스템 인덱스는 B-Tree/B+Tree를 선택한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 노드를 계층 구조로 연결해 정렬·탐색·계층 관계를 표현하는 자료구조
- 배경: 선형 구조(배열·리스트)는 데이터가 늘어나면 탐색 또는 삽입 비용이 O(n)까지 증가함
- 필요성: 균형 트리·다분기 트리는 트리 높이를 제어해 검색·인덱스·라우팅 테이블의 비용을 낮은 수준으로 제한

---

## Ⅱ. 구조 및 구성요소

```text
Root -> Internal Node -> Leaf
     / BST: left key < root < right key
     / AVL/Red-Black: rotation and recolor
     / B-Tree: multi-key page node
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Root | 탐색 시작 노드 | 부모 없음 |
| Internal Node | 분기 판단 | key와 child pointer 보유 |
| Leaf | 말단 데이터 위치 | B+Tree는 leaf 연결로 범위 탐색 |
| Balance Rule | 높이 제어 | AVL 높이차, Red-Black 색 규칙 |

> 요약: 트리는 Root에서 Leaf까지의 높이를 낮게 유지할수록 탐색·수정 비용을 O(log n)에 가깝게 제한한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 입력 -> 루트 비교 -> 좌/우 또는 자식 포인터 선택 -> 리프 도달 -> 회전/분할 보정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 검색 키와 현재 노드 키 비교 | BST: left < key < right |
| 2 | 자식 포인터 선택 | 비교 1회당 탐색 범위 축소 |
| 3 | 삽입·삭제 수행 | leaf 또는 대체 노드 처리 |
| 4 | 균형 보정 | AVL 회전, Red-Black recolor, B-Tree split/merge |

> 요약: 트리 연산은 비교로 경로를 선택하고, 수정 후 균형 규칙을 복구해 높이 증가를 제한한다.

---

## Ⅳ. 특징

| 구분 | AVL Tree | Red-Black Tree | B-Tree |
|:---|:---|:---|:---|
| 균형 기준 | |h(left)-h(right)| ≤ 1 | red/black 색 규칙 | 비루트 노드 키 수 ⌈m/2⌉-1 ~ m-1 |
| 탐색 비용 | O(log n) | O(log n) | O(log_m n) |
| 수정 비용 | 삽입 최대 2회, 삭제 최대 O(log n) 회전 | 삽입 최대 2회, 삭제 최대 3회 회전 | split/merge, 디스크 페이지 단위 |
| 적용 | 검색 비중 높은 메모리 구조 | OS·라이브러리 map/set | DBMS·파일시스템 인덱스 |

> 요약: AVL은 검색 비용 예측, Red-Black은 수정 균형, B-Tree는 페이지 I/O 감소가 판단 기준이다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 배열/해시 | 트리 구조 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 배열 정렬, 해시 버킷 | 계층 노드와 균형 규칙 | 범위 검색·정렬 순회 필요 시 트리 |
| 비용/성능 | 해시 평균 O(1), 범위 취약 | 균형 시 O(log n) | 업데이트와 range query 혼재 시 |
| 운영/위험 | 리사이징·충돌 | 회전·분할·동시성 latch | DB는 B+Tree, 메모리는 RB/AVL |

> 요약: 트리는 정렬·범위·동적 수정이 함께 필요한 경우 해시와 배열보다 일관된 비용을 제공한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 편향 트리 | 균형 규칙 없음 | AVL/Red-Black 회전 적용 | tree height <= 2log2 n |
| 페이지 분할 비용 | B-Tree 노드 overflow | fill factor 70~90%, bulk load | page split count |
| 동시성 병목 | 루트·상위 노드 latch 경합 | latch coupling, optimistic read | latch wait time |

> 요약: 트리 리스크는 높이 증가, 페이지 분할, latch 경합이며 높이와 대기시간으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐색 비용 | O(log n) 높이 유지 | height metric, benchmark |
| 범위 질의 | leaf scan 처리량 목표 충족 | DB explain, I/O 통계 |
| 무결성 | 정렬·균형 규칙 100% 통과 | invariant test |

> 요약: 트리 도입 효과는 높이, 범위 질의 처리량, 균형 불변식으로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. DB 인덱스: B+Tree leaf 연결로 `BETWEEN A AND B` 범위 검색을 leaf scan으로 처리
2. 메모리 정렬 집합: Red-Black Tree로 삽입·삭제 O(log n), Java TreeMap·C++ map 사례 적용
3. 읽기 중심 구조: AVL Tree로 높이 균형을 엄격히 유지하고 조회 지연 변동을 제한

**결론 (2줄):**
- 기술사 판단: 데이터가 디스크 페이지 단위이면 B-Tree, 메모리 내 동적 정렬 집합이면 Red-Black/AVL을 선택함
- 향후 방향: 동시성 환경에서는 latch coupling, copy-on-write B-Tree, lock-free tree 적용 여부를 검토해야 함
