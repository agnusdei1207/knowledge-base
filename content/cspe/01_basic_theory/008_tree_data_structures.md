## 미리 알고가기

- 루트: 트리의 시작 노드이며 부모가 없는 최상위 노드임
- 높이: 루트에서 가장 깊은 리프까지의 간선 수이며 탐색 비용에 영향을 줌
- 균형 트리: 높이가 한쪽으로 치우치지 않도록 삽입·삭제 후 구조를 조정하는 트리임
- B-Tree: 하나의 노드가 여러 키와 자식을 가지며 디스크/페이지 접근을 줄이는 다진 트리임
- AVL/RB Tree: 회전과 균형 조건으로 탐색 높이를 제한하는 이진 탐색 트리 계열임

## Ⅰ. 개요

- **정의**: 트리 구조는 노드와 간선으로 계층 관계를 표현하고, 키 순서나 부모-자식 관계를 기준으로 탐색·삽입·삭제·범위 질의를 수행하는 비선형 자료구조임. B-Tree, AVL, Red-Black Tree는 높이 또는 페이지 접근 수를 제어해 데이터가 커져도 검색 비용을 예측 가능하게 유지하기 위해 사용함.
- **배경/필요성**: 트리는 배열이나 해시 테이블이 표현하기 어려운 계층, 정렬 순회, 범위 검색을 자연스럽게 처리함. 단, 균형 유지 방식과 저장 매체 특성에 따라 선택 기준이 달라지므로 구조별 차이를 구분해야 함.
- **비유**: 조직도처럼 위아래 관계를 유지하면서, 특정 부서나 직원을 빠르게 찾아가기 위한 안내 체계와 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 트리 계열 자료구조 선택 역량 확인 | 계층 구조, 높이, 균형, 회전, 페이지 접근 | B-Tree와 이진 트리 혼동 |

> 요약: 트리는 계층과 정렬 관계를 구조화하고, 균형 유지로 탐색 비용을 제한하는 자료구조임.

## Ⅱ. 특징/비교

| 판단 기준 | B-Tree | AVL Tree | Red-Black Tree |
|:---|:---|:---|:---|
| 구조 | 노드 하나에 여러 키와 자식 저장 | 높이 차를 엄격히 제한 | 색상 규칙으로 대략적 균형 유지 |
| 탐색 비용 | 페이지 수 기준 `O(log_m n)` | `O(log n)` | `O(log n)` |
| 갱신 비용 | 분할·병합 발생 | 회전이 비교적 자주 발생 | 회전 횟수가 상대적으로 적음 |
| 적합 환경 | DB 인덱스, 파일시스템 | 조회가 많고 엄격한 균형 필요 | 범용 맵/셋, 갱신 빈번 |
| 선택 기준 | 블록 I/O 최소화 | 탐색 최적화 | 삽입·삭제 균형과 구현 안정성 |

> 요약: 트리 선택은 메모리 내부 탐색인지 디스크 페이지 접근인지, 조회와 갱신 중 무엇이 우선인지로 결정됨.

- 균형을 유지하지 않는 이진 탐색 트리는 정렬 입력에서 높이가 `n`까지 커질 수 있음
- B-Tree의 차수는 한 노드에 저장 가능한 키 수와 저장장치 페이지 크기에 맞춰 결정됨
- AVL은 탐색이 빠르지만 갱신 비용이 크고, Red-Black은 갱신과 탐색의 균형이 좋음

## Ⅲ. 구성요소

```text
+----------+
| Root     |
+----------+
    |
    v
+----------+      +----------+
| Key/Node | ---> | Children |
+----------+      +----------+
    |                    |
    v                    v
+----------+      +----------+
| Balance  |      | Leaves   |
+----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 루트 노드 | 탐색이 시작되는 최상위 노드이며 전체 트리의 진입점임 | 조직도 대표 |
| 키와 데이터 | 노드에 저장되는 검색 기준과 실제 값 또는 값의 위치임 | 부서 코드와 문서 |
| 자식 포인터 | 하위 노드로 이동하는 연결이며 키 범위별 분기를 제공함 | 하위 부서 연결 |
| 균형 정보 | 높이, 색상, 키 개수처럼 균형을 유지하기 위한 메타데이터임 | 층수 관리표 |
| 리프 노드 | 더 이상 자식이 없는 끝 노드이며 B+Tree에서는 데이터 접근 지점이 됨 | 말단 창구 |

> 요약: 트리는 루트에서 키 비교로 자식을 선택하고, 균형 정보를 이용해 높이를 통제하는 구조임.

- 이진 탐색 트리는 왼쪽 자식이 작은 키, 오른쪽 자식이 큰 키라는 순서 불변식을 유지함
- B-Tree는 한 노드의 여러 키가 자식 범위를 나누므로 비교와 I/O 비용을 함께 고려함
- 균형 메타데이터가 잘못되면 탐색 결과보다 먼저 높이 제한이 깨질 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 키입력   | ---> | 노드탐색 | ---> | 갱신수행 | ---> | 균형복구 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 비교기준 |      | 분기선택 |      | 삽입/삭제|      | 회전/분할|
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 탐색, 삽입, 삭제, 범위 질의, 저장 매체 특성을 확인해 트리 종류를 선택함
2. **키 기반 탐색** - 루트에서 시작해 키 비교 또는 키 범위 판단으로 하위 노드를 선택함
3. **갱신 처리** - 원소를 찾거나 삽입·삭제하고, 필요한 경우 노드 분할·병합 또는 회전을 수행함
4. **균형 검증** - 높이 차, 색상 규칙, 노드 키 개수 범위 같은 불변식을 확인하고 결과를 반환함

> 요약: 트리 절차는 키 비교로 경로를 좁히고 갱신 후 균형 불변식을 복구하는 흐름임.

- 범위 질의는 시작 키 탐색 후 중위 순회 또는 리프 연결 순회로 처리함
- 삭제는 후계자 대체, 병합, 재균형까지 포함되어 삽입보다 구현 위험이 큼
- 동시성 인덱스에서는 노드 단위 latch와 구조 변경 연산을 별도로 제어해야 함

## Ⅴ. 문제점

- **P1 균형 유지 비용**: 삽입·삭제가 잦으면 회전, 색상 변경, 노드 분할·병합이 반복되어 갱신 지연이 커질 수 있음
- **P2 구조 선택 불일치**: 메모리 내부 자료에 B-Tree를 과도하게 적용하거나 디스크 인덱스에 이진 트리를 쓰면 접근 비용이 비효율적임
- **P3 동시 갱신 복잡성**: 여러 작업이 같은 노드나 경로를 갱신하면 잠금 경합과 구조 변경 충돌이 발생할 수 있음

> 요약: 트리 운영 리스크는 균형 복구 비용, 저장 매체와 구조 불일치, 동시 갱신 통제에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 조회/갱신 비율에 따라 AVL, Red-Black, B-Tree를 선택하고 재균형 횟수를 모니터링함 (확인: 회전·분할 횟수)
- **P2 대응**: 메모리는 Red-Black/AVL, 디스크와 DB 인덱스는 B/B+Tree처럼 접근 단위에 맞게 구조를 매핑함 (확인: 캐시 미스와 I/O 횟수)
- **P3 대응**: 노드 단위 잠금, latch coupling, copy-on-write, MVCC 등으로 구조 변경 충돌을 제어함 (확인: 경합률과 대기 시간)

> 요약: 트리 개선은 워크로드와 저장 매체에 맞는 균형 전략을 선택하고 동시 갱신을 안전하게 통제하는 것임.

## Ⅶ. 전망

- **향후 발전 방향**: 데이터베이스와 파일시스템에서는 B+Tree 변형, LSM Tree, 메모리 친화 인덱스가 함께 비교되는 방향으로 발전함
- **기술사적 판단**: 트리는 높이와 균형 조건만 외우지 말고 조회/갱신 비율, 범위 질의, 저장 매체를 기준으로 선택해야 함
- **기술사 제언**: 답안에서는 B-Tree, AVL, Red-Black을 같은 트리로 묶되 선택 기준을 I/O, 탐색, 갱신 비용으로 나누어 제시해야 함

> 요약: 트리 구조는 계층·정렬·범위 질의를 동시에 다루는 핵심 구조이며, 균형 전략 선택이 기술사 판단의 중심임.
