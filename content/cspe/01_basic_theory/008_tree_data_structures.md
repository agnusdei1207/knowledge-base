# 008. 트리 구조 (Tree Data Structures) [출제: 122, 137회]

## Ⅰ. 개요

- **정의/개념**: 데이터 편향으로 인한 성능 저하를 막기 위해 스스로 균형을 유지하는 자가 균형 이진 탐색 트리(AVL, Red-Black) 및 다진 탐색 트리(B-Tree)의 총칭임
  - **AVL 트리**: 좌우 서브트리의 높이 차이를 $1$ 이하로 엄격하게 제한하는 균형 트리임
  - **Red-Black 트리**: 노드에 색상을 부여하여 높이 균형을 느슨하게 관리하는 효율적 범용 트리임
  - **B-Tree**: 하나의 노드에 여러 키를 저장하여 트리 높이를 낮춘 디스크 최적화 다진 트리임
- **배경/필요성**: 일반 이진 탐색 트리($BST$)는 데이터 삽입 순서에 따라 높이가 $O(n)$까지 비대해지는 편향 문제가 발생함. 이를 해결하기 위해 최악의 경우에도 탐색 성능 $O(\log n)$을 보장하는 구조적 자동 균형 메커니즘이 필수적임

## Ⅱ. 특징 및 비교

세 구조 모두 최악의 경우에도 높이를 $O(\log n)$으로 제한하지만, 균형 유지의 엄격함과 주 저장 매체에 따라 활용도가 달라짐.

| 구분 | AVL (Adelson-Velsky and Landis) | Red-Black Tree | B-Tree |
|:---|:---|:---|:---|
| **균형 방식** | 좌우 높이차 $\leq 1$ (엄격) | Red/Black 색상 규칙 (느슨) | 노드당 다중 키 ($M$원 탐색) |
| **갱신 비용** | 회전 (Rotation) 빈도 높음 | 회전 빈도 낮음 | 노드 분할 (Split) 및 병합 |
| **탐색 성능** | 가장 우수 (최상 균형) | 우수 (실질적 최적) | 디스크 I/O 횟수 최소화 |
| **주요 용도** | 조회 위주 메모리 DB | 범용 Map/Set 자료구조 | DB 인덱스, 파일 시스템 |

> 요약: 정밀한 조회가 우선이면 AVL, 삽입/삭제가 빈번하면 Red-Black, 대용량 외부 저장은 B-Tree가 적합함.

## Ⅲ. 구성요소/구조

트리 아키텍처는 노드 내의 키 배치와 자식 포인터의 분기 구조로 결정됨.

- **핵심 구조도 (ASCII)**:

```text
        [50]
       /    \
    [30]    [70]        정렬 불변식: 좌측 서브트리 < 부모 < 우측 서브트리
    /  \    /  \
 [20][40][60][80]       균형 메커니즘: 높이차(AVL), 색상(R-B), 차수(B-Tree)
```

- **주요 구성요소**:
  1. **노드 (Node)**: 키 ($Key$)와 데이터, 그리고 자식 노드를 가리키는 포인터를 포함하는 기본 단위임
  2. **루트 (Root)**: 트리의 최상단 노드이며 탐색의 시작점임
  3. **균형 정보**: AVL의 `BF (Balance Factor)`, Red-Black의 `Color`, B-Tree의 `Key Count` 등을 의미함
  4. **회전 (Rotation)**: 균형이 깨졌을 때 노드의 위치를 변경하여 높이를 조정하는 핵심 연산임

## Ⅳ. 문제점 및 개선방안

1. **편향 트리 (Skewed Tree) 발생**: 자가 균형 기능이 없는 $BST$는 최악의 경우 탐색 속도가 $O(n)$으로 선형화됨
   - **개선방안**: 삽입·삭제 시 $O(\log n)$ 이내에 균형을 재조정하는 자가 균형 트리(AVL/RB)를 적용함 (확인: 최악 높이 보장 여부)

2. **잦은 재균형 오버헤드**: AVL 트리는 균형이 깨질 때마다 복잡한 회전을 수행하여 쓰기 성능이 저하됨
   - **개선방안**: 쓰기 비중이 높다면 균형 조건을 완화한 Red-Black 트리를 채택하여 회전 빈도를 낮춤 (확인: 갱신 지연시간 분포)

3. **디스크 I/O 병목**: 이진 트리는 노드당 키가 하나뿐이라 대용량 데이터 처리 시 트리 높이가 높아져 디스크 접근 횟수가 증가함
   - **개선방안**: 블록 단위 읽기에 최적화된 B-Tree를 사용해 트리 높이를 낮추고 I/O를 최소화함 (확인: 질의당 페이지 접근 횟수)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터베이스 (MySQL, Oracle) | **B+Tree** 구조로 인덱스를 생성하여 대량 데이터 검색 최적화 | Page Reads, Query Latency |
| OS 커널 (Linux) | 가상 메모리 관리, 스케줄러 등에서 **Red-Black Tree**로 효율적 관리 | Context Switch Time, Mem Latency |
| 언어 라이브러리 (Java, C++) | `TreeMap`, `std::map`의 기본 구현체로 **Red-Black Tree** 채택 | Insertion/Search Time Complexity |

## Ⅵ. 결론

트리 자료구조는 배열의 정렬 상태 유지와 연결 리스트의 삽입/삭제 편의성을 동시에 취하기 위한 핵심 도구임. 기술사는 단순히 구조를 외우는 것에 그치지 않고, 워크로드의 조회 대 갱신 비율, 그리고 저장 매체가 메모리인지 디스크인지에 따라 AVL, Red-Black, B-Tree 중 최적의 아키텍처를 선택할 수 있는 설계 역량을 갖추어야 함.
