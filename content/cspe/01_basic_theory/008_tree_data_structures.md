# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 트리는 노드들이 1:N으로 연결되어 계층적 관계(부모-자식)를 표현하는 비선형 자료구조다.
- **왜 필요한가**: 배열이나 연결 리스트 같은 선형 구조는 계층(조직도, 파일 시스템)을 표현하거나 대용량 데이터를 고속 검색하는 데 한계가 있어 고안되었다.
- **핵심 직관**: 회사의 조직도. 사장님(루트) 밑에 부장(자식)들이 있고, 부장 밑에 과장들이 뻗어 나가는 나무(Tree)를 거꾸로 뒤집어 놓은 형태다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 루트 (Root) | 트리의 가장 꼭대기에 있는 유일한 시작 노드 | 조직도의 사장님, 파일 시스템의 `C:\` |
| 리프 (Leaf) | 자식이 하나도 없는 맨 끝단의 단말 노드 | 조직도의 평사원 |
| 깊이/레벨 (Depth/Level) | 루트로부터 특정 노드까지 내려온 단계 수 | 사장=0, 부장=1, 과장=2 계급 |
| 차수 (Degree) | 어떤 노드가 가진 자식의 수 (트리의 차수 = 노드 중 최대 차수) | 부장 밑에 직원이 3명 있으면 부장의 차수는 3 |

## 깊이 이해
- **배경·문제의식**: 선형 구조(배열, 연결 리스트)는 나열하기는 좋지만 "분류"나 "계층"을 표현할 수 없다. 또한 정렬된 배열은 탐색은 O(log N)으로 빠르나 중간에 데이터를 끼워 넣으려면 O(N)이 걸린다. 이를 해결하기 위해 O(log N)의 탐색과 유연한 삽입/삭제를 동시에 잡으려는 시도가 트리의 출발이다.
- **작동 원리 (이진 트리 기준)**:
  - 각 노드는 최대 2개의 자식(왼쪽, 오른쪽)을 가진다.
  - 이진 탐색 트리(BST): 왼쪽 자식은 나보다 작고, 오른쪽 자식은 나보다 크다. 값을 찾을 때 루트부터 시작해 크면 오른쪽, 작으면 왼쪽으로 내려가면 탐색 범위가 절반씩 줄어든다 (O(log N)).
- **비유**: 스무고개 게임. "50보다 크니?" -> "아니" (왼쪽 가지로 감) -> "25보다 크니?" -> "응" (오른쪽 가지로 감).
- **흔한 오해·주의점**: "트리는 항상 O(log N)으로 빠르다"는 오해다. 한쪽으로만 계속 자식이 달린 편향 트리(Skewed Tree)가 되면, 결국 선형 리스트와 다를 바 없어져 최악의 경우 O(N)으로 추락한다. 이를 방지하기 위해 좌우 균형을 억지로 맞추는 AVL 트리나 Red-Black 트리(균형 트리)가 실무에서 쓰인다.

## 연결 개념
- 이진 탐색 (004 참조): 배열에서의 이진 탐색 원리를 비선형 자료구조로 구현한 것이 이진 탐색 트리(BST).
- B-Tree (DB 인덱스): 이진 트리를 다진(Multi-way) 트리로 확장하여 디스크 I/O를 최소화한 형태.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 트리는 노드 간의 1:N 계층 관계를 포인터로 연결한 비선형 자료구조로, 사이클(Cycle)이 없는 연결 그래프의 일종이다.
> 2. **가치**: 탐색(Search)과 삽입/삭제(Update)를 모두 O(log N)으로 수렴시키기 위한 기반 구조이며, 계층적 데이터(조직도, 디렉터리) 모델링에 필수적이다.
> 3. **판단 포인트**: 트리가 한쪽으로 치우치는 편향(Skewed) 현상을 막고 좌우 밸런스를 유지하는 자가 균형 트리(Red-Black Tree, B-Tree) 아키텍처 채택이 성능의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층적 비선형 구조의 특징 이해 | 사이클이 없는 연결 그래프, 부모-자식(1:N) 관계 | 노드, 간선 용어 혼동 및 그래프 구조와의 차이 누락 |
| 이진 트리의 진화 및 탐색 원리 | 편향 트리 문제점(O(N)) 및 균형 트리의 해결책 | 트리 종류(AVL, RB) 나열에 그치고 O(log N) 원리 누락 |
| 실무 활용 아키텍처 매핑 역량 | Red-Black Tree (In-memory), B-Tree (Disk I/O) 매핑 | 추상적 개념만 서술하고 DB/OS의 실제 적용처 누락 |

> 요약: 트리의 계층적 탐색 원리(O(log N))를 짚고, 편향 시 발생하는 O(N) 성능 저하를 방어하기 위한 자가 균형(Self-Balancing) 트리의 실무적 가치를 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 트리는 사이클(Cycle)이 없이 노드들이 1:N 계층적 관계를 이루는 비선형 자료구조로, 이진 탐색의 동적 확장을 지원함
- 배경: 선형 자료구조(배열, 리스트)는 빠른 탐색(O(log N))과 빠른 갱신(O(1))을 동시에 충족할 수 없는 구조적 모순이 존재함
- 필요성: RDBMS 인덱스 관리, XML/JSON 파싱, 파일 시스템 등에서 동적 데이터의 고속 검색과 계층적 관리가 모두 필요함

---

## Ⅱ. 구조 및 구성요소

```text
       [Root (Depth 0)]
       /              \
 [Node A (Depth 1)]  [Node B (Depth 1)]
    /      \               \
[Leaf C]  [Leaf D]        [Leaf E (Depth 2)]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드 (Node) / 간선 (Edge) | 데이터 단위(Node)와 이를 잇는 연결선(Edge) | 노드가 N개면 간선은 반드시 N-1개 |
| 루트 (Root) / 리프 (Leaf) | 트리의 유일한 진입점(Root)과 최하단 끝점(Leaf) | 루트로의 집중 병목 관리 필요 |
| 깊이 (Depth) / 높이 (Height) | 루트에서 특정 노드까지의 거리(Depth) 및 트리의 최대 깊이(Height) | 트리의 높이(h)가 탐색 복잡도 O(h)를 결정 |

> 요약: 단일 루트에서 시작해 간선을 통해 리프까지 뻗어나가는 계층 구조이며, 전체 트리의 높이가 탐색 성능을 좌우한다.

---

## Ⅲ. 동작원리 및 흐름도 (이진 탐색 트리 검색 기준)

```text
Root 진입 -> Target과 값 비교 -> [일치] 성공 반환
                               |
                               +-> [Target < Node] 왼쪽 자식으로 이동
                               +-> [Target > Node] 오른쪽 자식으로 이동 -> 리프 도달 시 실패
```

- 1단계 [진입 및 비교]: 트리의 유일한 진입점인 `Root` 노드부터 탐색을 시작하여 찾고자 하는 값(`Target`)과 비교
- 2단계 [좌우 분기]: 이진 탐색 트리(BST)의 특성(좌<루트<우)을 이용해, 타겟이 작으면 왼쪽 간선, 크면 오른쪽 간선으로 이동
- 3단계 [재귀 탐색]: 이동한 서브 트리를 새로운 Root로 간주하여 1~2단계를 반복하며 탐색 범위 축소
- 4단계 [종료 판정]: 값을 찾거나, Leaf 노드를 넘어 Null 포인터에 도달하면 탐색 종료(O(h) 소요)

> 요약: 각 노드에서 대소 비교를 통해 하위 서브 트리 중 절반을 버리는 분할 정복(Divide & Conquer)을 통해 O(log N) 시간에 탐색한다.

---

## Ⅳ. 특징

- O(log N) 탐색/갱신 균형: 탐색 성능이 우수한 배열과 삽입/삭제가 우수한 연결 리스트의 장점을 혼합한 하이브리드 성능 제공
- 사이클 부재 (Acyclic): 그래프와 달리 노드 간 순환(Cycle) 궤적이 존재하지 않아 무한 루프에 빠지지 않고 단방향 경로를 보장
- 치우침 취약성 (Skewed): 정렬된 데이터가 순서대로 삽입될 경우, 일렬로 늘어선 편향 트리가 되어 탐색 시간이 O(N)으로 붕괴함

> 요약: 이론적으로 O(log N)의 우수한 동적 성능을 보장하나, 입력 데이터 패턴에 따라 밸런스가 무너지면 선형 구조로 퇴화하는 한계가 있다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 이진 탐색 트리 (BST) | 자가 균형 트리 (Red-Black) | B-Tree (다진 트리) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 균형 관리 | 없음 (최악 편향 시 O(N)) | 색상 회전으로 높이 O(log N) 억제 | 다수 자식 노드로 트리 높이 평탄화 | 성능 보장 요구 수준 |
| 메모리/I/O | 포인터 2개 (In-Memory) | 추가 색상 비트 (In-Memory) | 한 노드에 다수 Key (Disk I/O) | 디스크 접근 여부 |
| 활용처 | 기본 알고리즘/학술 구현 | Java HashMap 체이닝, 리눅스 스케줄러 | RDBMS 인덱스(B+Tree) | 캐시 적중률 및 물리 매체 |

> 요약: 단순 BST는 최악의 상황(O(N))을 방어하지 못하므로, 실무의 메모리 환경에서는 Red-Black 트리를, 디스크 환경에서는 B-Tree를 채택한다.

**리스크·대응 (기본은 불릿):**
- 편향 트리(Skewed Tree) 붕괴 리스크: 순차적 데이터 삽입으로 트리가 한쪽으로 쏠려 O(N) 지연 발생 -> AVL 트리의 팩터(Factor) 계산이나 Red-Black 트리의 색상 회전(Rotation) 기법으로 강제 균형 유지 (지표: 트리의 좌우 서브트리 높이 차이)
- 잦은 삽입/삭제 밸런싱 오버헤드: 균형 트리에서 데이터 변경 시마다 회전 연산 발생으로 CPU 소모 폭증 -> 일괄(Batch) 갱신 처리 또는 읽기 비율이 90% 이상인 데이터 스토어로 용도 제한 (지표: 트리 Rebalancing 소요 시간)

**도입 후 점검 지표 (기본은 불릿):**
- 성능/효율: 데이터 건수 N 증가에 따른 최대 탐색 Depth (Height 증가율) — O(log N) 궤적 실측
- 품질/운영: 디스크 인덱스의 경우 노드 분할(Split) 발생 횟수 — B-Tree 페이지 단편화 모니터링

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 인덱스 아키텍처: 디스크 블록 크기에 맞춰 노드를 넓게(Multi-way) 구성한 B+Tree를 적용하여, 디스크 I/O 횟수를 3~4회(Depth) 수준으로 억제한 O(log N) 고속 범위 검색 구현
2. 메모리 충돌 캐시: Java 8+의 HashMap에서 특정 버킷에 해시 충돌이 8개 이상 누적 시, 선형 리스트(O(N))를 Red-Black Tree(O(log N))로 변환하여 Hash DoS 공격 방어
3. 계층형 데이터 파싱: XML/JSON 파서, HTML DOM 트리 구성 시 데이터를 N-ary(다진) 트리 구조로 메모리에 로드하여 XPath, CSS Selector 기반의 계층적 렌더링 및 탐색 구현

**결론 (2줄):**
- 기술사 판단: 트리는 데이터의 논리적 계층을 물리적 탐색 효율성으로 치환한 최적의 구조이나, 실무에서는 편향을 막기 위한 O(log N) 밸런싱 오버헤드를 아키텍처에 반드시 감안해야 함
- 향후 방향: 최근 대용량 인-메모리 DB에서는 캐시 라인(Cache Line) 적중률을 극대화하기 위해, 이진 트리보다 노드가 비대한 B-Tree 계열 구조를 메모리 환경에도 재도입(T-Tree 등)하는 추세임
