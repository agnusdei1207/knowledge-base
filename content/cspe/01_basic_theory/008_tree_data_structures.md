## 미리 알고가기

- 트리 높이: 루트에서 가장 깊은 리프까지의 경로 길이이며 탐색 비용을 좌우함
- 균형 트리: 삽입·삭제 후 높이가 과도하게 커지지 않도록 회전·분할로 구조를 조정하는 트리임
- 다진 트리: 한 노드가 여러 키와 여러 자식을 가져 디스크·페이지 단위 접근에 적합한 트리임

## Ⅰ. 개요

- **정의**: 계층적 부모-자식 관계로 데이터를 표현하는 비선형 자료구조임
- **배경/필요성**: 정렬된 데이터의 탐색·삽입·삭제를 효율적으로 처리하려면 선형 구조보다 높이를 통제하는 계층 구조가 필요함
- **비유**: 조직도처럼 상위 노드에서 하위 노드로 범위를 좁혀 내려가는 구조임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 균형 트리와 저장매체별 선택 기준 비교 | BST, AVL, Red-Black, B-Tree, 높이, 회전, 페이지 | 단순 이진트리와 균형트리 혼동, B-Tree 용도 누락 |

> 요약: 트리는 높이와 균형 유지 방식에 따라 탐색 성능과 운영 용도가 달라짐.

## Ⅱ. 특징/비교

| 판단 기준 | AVL Tree | Red-Black Tree | B-Tree |
|:---|:---|:---|:---|
| 균형 기준 | 좌우 높이 차를 엄격히 제한 | 색 규칙으로 완화 균형 유지 | 다수 키와 자식으로 높이 감소 |
| 연산 특성 | 탐색에 유리, 회전 잦음 | 삽입·삭제 비용 균형 | 디스크·DB 인덱스에 유리 |
| 선택 기준 | 읽기 비중 높은 메모리 구조 | 범용 맵·셋 구현 | 페이지 단위 I/O 절감 |

> 요약: AVL은 엄격 균형, Red-Black은 범용 균형, B-Tree는 저장매체 친화성이 선택 기준임.

- 균형이 깨진 BST는 정렬된 입력에서 연결 리스트처럼 높이가 `n`까지 증가함
- B-Tree는 노드 하나에 여러 키를 저장해 디스크 접근 횟수를 줄이는 데 목적이 있음
- 트리 선택은 이론 복잡도뿐 아니라 읽기/쓰기 비율과 저장매체 접근 단위로 결정해야 함

## Ⅲ. 구성요소

```text
+----------+
| Root     |
+----------+
     |
     v
+----------+      +----------+
| Internal | ---> | Leaf     |
+----------+      +----------+
     |
     v
+----------+
| Balance  |
+----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Root | 탐색이 시작되는 최상위 노드임 | 조직도 대표 |
| Internal Node | 키 비교 후 하위 노드로 탐색 범위를 좁히는 중간 노드임 | 부서장 |
| Leaf Node | 실제 탐색 종료 지점 또는 데이터 참조가 위치하는 말단 노드임 | 실무 담당자 |
| Balance Rule | 회전, 색 규칙, 노드 분할로 높이를 통제하는 규칙임 | 조직 층수 조정 |

> 요약: 트리는 루트에서 리프까지 내려가며, 균형 규칙으로 높이를 통제함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 키비교   | ---> | 하위이동 | ---> | 삽입/삭제 | ---> | 균형조정 |
+----------+      +----------+      +----------+      +----------+
```

1. **키 비교**: 현재 노드의 키와 탐색 키를 비교함
2. **하위 이동**: 비교 결과에 따라 왼쪽·오른쪽 또는 해당 자식 포인터로 이동함
3. **삽입/삭제**: 리프 또는 대상 위치에서 키를 추가하거나 제거함
4. **균형 조정**: 회전, 색 변경, 노드 분할·병합으로 높이 조건을 복구함

> 요약: 트리 연산은 키 비교로 범위를 좁히고 변경 후 균형 조건을 복구하는 흐름임.

## Ⅴ. 문제점

- **P1 높이 증가**: 단순 BST는 정렬 입력에서 한쪽으로 치우쳐 탐색·삽입·삭제가 `O(n)`으로 악화됨
- **P2 균형 유지 복잡성**: AVL·Red-Black은 회전과 색 규칙 구현 오류가 구조 불변식 위반으로 이어질 수 있음
- **P3 저장매체 부적합**: 이진 균형 트리를 디스크 인덱스에 그대로 쓰면 노드 방문마다 랜덤 I/O가 증가함

> 요약: 트리 성능은 높이 통제, 불변식 구현, 저장매체 접근 단위가 관리될 때 유지됨.

## Ⅵ. 개선방안

1. **단기**: 트리 높이, 회전 횟수, 불변식 검사를 테스트에 포함함
2. **중기**: 읽기·쓰기 비율에 따라 AVL, Red-Black, B-Tree를 선택하는 기준을 수립함
3. **장기**: DB·파일 시스템은 B-Tree/B+Tree, 메모리 맵은 Red-Black·AVL 등 저장계층별 표준 구조를 분리함

- **P1 대응**: 균형 트리를 적용해 높이를 `O(log n)` 수준으로 제한함 (확인: 최대 높이)
- **P2 대응**: 회전·색 규칙을 자동 검증하고 경계 삭제 테스트를 강화함 (확인: 불변식 검사)
- **P3 대응**: 디스크·SSD 환경은 페이지 친화적인 B-Tree 계열을 적용함 (확인: 페이지 읽기 횟수)

> 요약: 트리 개선은 균형 유지와 저장계층 적합성을 동시에 보는 방향이어야 함.

## Ⅶ. 전망

- 인메모리 자료구조에서는 Red-Black, AVL, skip list가 용도별로 유지되고, 저장소 계층에서는 B-Tree와 LSM Tree가 계속 경쟁함
- 클라우드 DB와 대용량 인덱스에서는 트리 높이보다 페이지 캐시, 쓰기 증폭, 압축 효율이 선택 기준으로 결합됨
- 기술사는 트리 종류를 나열하기보다 읽기/쓰기 비율, 정렬 순회, 저장매체 비용을 연결해 판단해야 함
