# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 트리 자료구조는 **노드를 부모-자식 계층으로 연결**한 비선형 구조이며, 그중 탐색용 균형 트리(AVL·Red-Black·B-Tree)는 **높이를 log N에 묶어** 탐색·삽입·삭제를 O(log N)에 보장하는 것이 핵심이다.
- **왜 필요한가**: 정렬 배열은 이진 탐색이 O(log N)이나 삽입·삭제가 O(N)이고, 이진 탐색 트리(BST)는 입력이 한쪽으로 치우치면 한 줄(높이 N)로 퇴화해 O(N)이 되기 때문이다. **균형을 강제로 맞춰** 최악에도 O(log N)을 지키려는 것이다.
- **핵심 직관**: "트리를 옆으로 기울지 않게 계속 세워 둔다" — 삽입·삭제 때마다 회전(AVL·RB)이나 노드 분할(B-Tree)로 높이를 낮게 유지하면, 뿌리에서 잎까지 몇 걸음이면 닿는다.

## 핵심 용어 정리 (내부에 등장하는 것들)

트리·균형·회전 용어를 먼저 세운다. 여기 정의한 노드·높이 개념은 순회를 다루는 009에서 참조로 재사용한다. 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 균형 탐색 트리 (상위 키워드) | 높이를 log N에 유지해 O(log N)을 보장하는 트리 | 늘 반듯이 세워 두는 서류 정리함 |
| 노드/루트/리프 | 데이터 한 칸 / 최상위 시작 노드 / 자식 없는 끝 노드 | 조직도의 한 사람 / 최고경영자 / 말단 사원 |
| 높이(Height) | 루트에서 가장 먼 리프까지의 간선 수 | 조직도의 최대 직급 단계 수 |
| 이진 탐색 트리(BST) | 왼쪽<부모<오른쪽 정렬 규칙의 이진 트리 | 왼쪽엔 작은 것, 오른쪽엔 큰 것 |
| 편향(Skew) | 한쪽으로만 자라 높이가 N에 가까워진 상태 | 한 줄로 늘어선 도미노(사실상 리스트) |
| 회전(Rotation) | 부모-자식 관계를 재배치해 높이를 낮추는 연산 | 기운 저울을 축 삼아 되돌리기 |
| 균형 인수(Balance Factor) | 좌·우 서브트리 높이 차(AVL이 −1~+1로 유지) | 양팔 저울의 기울기 |
| B-Tree 차수(Order, m) | 한 노드가 가질 수 있는 최대 자식 수 | 한 서랍에 넣는 최대 칸막이 수 |
| 노드 분할/병합(Split/Merge) | B-Tree에서 꽉 찬·빈 노드를 나누거나 합치는 연산 | 꽉 찬 서랍을 둘로 나눔 / 빈 서랍 합침 |
| O(log N) | N이 2배로 늘어도 연산이 1회만 느는 성능 등급 | 100만 항목도 약 20걸음이면 도달(001·002 참조) |

## 깊이 이해
- **배경·문제의식**: BST는 평균 O(log N)이지만 정렬된 데이터를 순서대로 넣으면 오른쪽으로만 자라 높이가 N이 되고 탐색이 O(N)으로 무너진다. "**최악에도** O(log N)"을 보장하려면 삽입·삭제마다 균형을 회복시켜야 한다. AVL·Red-Black은 회전으로, B-Tree는 노드 분할로 이를 해결한다.
- **작동 원리 (어떻게+왜)**:
  - **AVL**: 모든 노드의 균형 인수를 −1~+1로 엄격히 유지한다. 삽입·삭제로 이를 벗어나면 즉시 회전(LL·RR·LR·RL)한다 — 가장 팽팽히 균형이라 탐색이 빠르지만 회전이 잦다.
  - **Red-Black**: "루트·리프는 검정, 빨강 노드의 자식은 검정, 임의 경로의 검정 노드 수 동일" 규칙으로 **느슨한 균형**(최장 경로 ≤ 최단 경로의 2배)만 유지한다 — 회전이 적어 삽입·삭제가 빠르다.
  - **B-Tree**: 한 노드에 여러 키를 담고 자식을 여럿(차수 m) 둔다. 노드가 꽉 차면 분할해 위로 올린다 — **높이가 매우 낮아** 디스크 접근 횟수를 줄인다.
- **비유**: AVL은 결벽증 사서(조금만 삐뚤어도 즉시 정리), Red-Black은 실용 사서(2배까지는 봐줌), B-Tree는 큰 서랍장(한 서랍에 여러 파일을 담아 서랍 여는 횟수를 줄임).
- **구체 예시(수치·사례)**: 100만 개(N=10⁶) 데이터에서 이진 균형 트리 높이는 약 20이지만, 차수 100인 B-Tree는 높이 3이면 담긴다 — 디스크 I/O가 20회에서 3회로 준다. 그래서 DB 인덱스·파일 시스템은 B-Tree/B+Tree를 쓴다.
- **흔한 오해·주의점**:
  - **"트리면 무조건 O(log N)"이 아니다.** 균형을 안 맞춘 일반 BST는 최악 O(N)이다. log N 보장은 균형 트리에 한한다.
  - AVL이 항상 최선은 아니다. **읽기 위주면 AVL, 삽입·삭제가 잦으면 회전이 적은 Red-Black**이 유리하다.
  - B-Tree가 이진 트리보다 "높이가 낮은" 이유는 노드당 자식이 많아서지, 데이터가 적어서가 아니다.

## 연결 개념
- **이진 트리 순회 (009)**: 여기서 세운 노드·서브트리 구조를 전위·중위·후위로 훑는 방문 방법.
- **해시 테이블 (005)**: 평균 O(1) 조회지만 정렬·범위 검색이 안 되는 대안 — 범위 질의엔 균형 트리가 유리.
- **B+Tree·DB 인덱스**: B-Tree를 리프 연결·데이터 분리로 개량한, 관계형 DB 인덱스의 사실상 표준.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 균형 탐색 트리는 삽입·삭제 시 회전(AVL·RB)·분할(B-Tree)로 높이를 log N에 묶어 최악에도 O(log N)을 보장함.
> 2. **가치**: BST 편향에 따른 O(N) 퇴화를 막아 인덱스·정렬 데이터 관리의 성능 하한을 확정함.
> 3. **판단 포인트**: 읽기 위주는 AVL, 갱신 잦으면 Red-Black, 디스크 대용량은 B-Tree로 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 균형화 필요성 이해 | BST 편향 시 O(N) 퇴화와 높이 log N 유지 원리 | 모든 트리가 O(log N)이라 단정 |
| 균형화 기법 구분 | AVL 엄격 균형·RB 느슨 균형·B-Tree 다분기 | AVL·RB 회전과 B-Tree 분할 혼동 |
| 용도별 선택 판단 | 읽기·쓰기 비율, 디스크 I/O 최소화 매핑 | 세 트리 성능 트레이드오프 누락 |

> 요약: BST 편향 방지라는 목적 아래 회전·분할 기법 차이와 읽기·쓰기·디스크 기준 선택을 함께 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 높이를 log N에 유지해 탐색·삽입·삭제를 O(log N)에 보장하는 균형 이진·다분기 트리임
- 배경: 일반 BST는 정렬 입력에 한쪽으로 편향돼 높이 N·탐색 O(N)으로 퇴화함
- 필요성: 대용량 인덱스·정렬 데이터에서 최악에도 log N 성능을 확정할 자가 균형 구조가 필요함

## Ⅱ. 구조 및 구성요소
선형 구조도 (균형 트리 계열):

    루트 -> 내부 노드 -> 리프 (부모 < 오른쪽 / 왼쪽 < 부모 : BST 정렬 규칙)
      / AVL       : 이진, 균형 인수 -1~+1 유지, 위반 시 회전
      / Red-Black : 이진, 색(빨강/검정) 규칙으로 최장<=2배 최단 유지
      / B-Tree    : 다분기(차수 m), 한 노드 다중 키, 포화 시 분할

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드·키 | 데이터와 정렬 기준 값 저장 | B-Tree는 한 노드에 다중 키 |
| 자식 포인터 | 하위 서브트리 연결 | 이진은 최대 2개, B-Tree는 최대 m개 |
| 균형 인수 / 색 | AVL 높이 차 / RB 노드 색으로 균형 판정 | 위반 시 회전 유발 |
| 분할·병합 로직 | B-Tree 포화·과소 노드 재구성 | 디스크 노드 크기와 정렬 |

> 요약: 세 트리 모두 정렬 규칙 위에 균형 장치(균형 인수·색·분할)를 얹어 높이를 log N에 묶음.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (삽입 후 균형 회복):

    키 삽입(BST 규칙 위치 탐색) -> 삽입 -> 균형 위반 검사 -> 회전 또는 분할 -> 균형 회복

1. 위치 탐색: 루트부터 정렬 규칙(작으면 왼쪽·크면 오른쪽)으로 삽입 지점까지 하강함(O(log N))
2. 삽입: 리프(또는 B-Tree 해당 노드)에 키를 넣음
3. 위반 검사: 삽입 노드에서 루트로 올라가며 AVL은 균형 인수, RB는 색 규칙, B-Tree는 노드 포화를 점검함
4. 균형 회복: AVL·RB는 회전(및 색 변경), B-Tree는 노드 분할로 높이를 다시 log N에 맞춤

> 요약: 정렬 규칙으로 삽입 후 루트 방향으로 위반을 검사하고, 회전·분할로 높이를 log N에 복원함.

## Ⅳ. 특징
- 최악 O(log N) 보장: 균형 장치로 편향을 차단해 탐색·삽입·삭제 상한을 확정함
- 정렬·범위 질의 지원: 중위 순회로 정렬 출력·구간 검색이 가능해 해시 테이블과 차별됨
- 자가 균형 비용: 삽입·삭제마다 회전·분할이 추가돼 순수 조회보다 갱신 비용이 큼
- 다분기 확장성: B-Tree는 노드당 자식을 늘려 높이를 낮추고 디스크 I/O 횟수를 최소화함

## Ⅴ. 심화 비교 및 적용 판단

균형 방식·구조·적합 환경 축에서 세 균형 트리를 대조함.

| 구분 | AVL Tree | Red-Black Tree | B-Tree |
|:---|:---|:---|:---|
| 균형 강도 | 엄격(높이 차 ≤1) | 느슨(최장 ≤ 2배 최단) | 다분기 높이 최소화 |
| 균형 수단 | 회전(즉시·잦음) | 색 변경·회전(드묾) | 노드 분할·병합 |
| 강점 연산 | 탐색(가장 낮은 높이) | 삽입·삭제(회전 적음) | 디스크 I/O(낮은 높이) |
| 적합 환경 | 읽기 위주 인메모리 | 갱신 잦은 인메모리(맵·셋) | 대용량 디스크 인덱스·파일시스템 |

> 요약: 읽기 위주면 AVL, 삽입·삭제가 잦으면 Red-Black, 디스크 대용량이면 B-Tree가 적합함.

**리스크·대응:**
- BST 편향 퇴화 — 정렬 입력으로 높이 N 발생 → 자가 균형 트리 채택·삽입 후 회전 검증
- 과도한 회전 비용 — AVL의 잦은 회전으로 갱신 지연 → 갱신 빈발 시 Red-Black으로 전환
- 디스크 노드 크기 불일치 — B-Tree 노드가 페이지 크기와 어긋나 I/O 낭비 → 차수를 페이지(4KB) 기준 산정

**점검 지표:**
- 성능: 탐색·삽입 평균 트리 높이 — 노드 수 대비 실측 높이 대조
- 효율: 질의당 디스크 I/O 횟수 — B-Tree 인덱스 프로파일링

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 관계형 DB 인덱스를 B+Tree로 구성해 범위 검색·정렬을 낮은 디스크 I/O로 O(log N)에 처리
2. 언어 표준 라이브러리 정렬 맵·셋(C++ std::map, Java TreeMap)을 Red-Black으로 구현해 갱신 잦은 정렬 컬렉션 지원
3. 파일 시스템 메타데이터(NTFS·이후 계열)를 B-Tree 계열로 관리해 대용량 디렉터리 탐색을 가속

**결론:**
- 기술사 판단: 인메모리·읽기 위주는 AVL, 갱신 빈발은 Red-Black, 디스크 대용량은 B-Tree로 선택하는 조건부 판단이 유효함
- 향후 방향: SSD·대용량 환경에서 쓰기 증폭을 줄이는 LSM-Tree·B+Tree 변형이 스토리지 인덱스의 핵심 대안으로 확대되는 추세임
