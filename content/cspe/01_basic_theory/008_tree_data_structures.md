## 미리 알고가기

- 균형 트리: 트리 높이가 한쪽으로 과도하게 치우치지 않도록 제어해 탐색 성능을 안정적으로 유지하는 트리임
- 회전: 부모와 자식의 연결 관계를 다시 배치해 높이 불균형을 줄이는 연산임
- 차수: 한 노드가 가질 수 있는 자식 수이며, B-Tree에서는 트리 높이와 페이지 읽기 횟수에 직접 영향을 줌

## Ⅰ. 개요

- **정의/개념**: 트리 구조는 부모와 자식의 계층 관계로 데이터를 조직해 비교 경로를 분기하는 비선형 자료구조이며, AVL 트리, Red-Black 트리, B-Tree는 삽입과 삭제 뒤에도 높이나 노드 구성을 제어해 탐색 성능을 일정하게 유지하는 대표 균형 트리 계열임
- **배경/필요성**: 단순 이진 탐색 트리는 입력이 한쪽으로 몰리면 높이가 커져 탐색 시간이 선형으로 악화되므로, 메모리 기반 탐색과 디스크 기반 인덱스 모두에서 균형 유지 전략이 필요함

## Ⅱ. 특징

- AVL 트리는 왼쪽과 오른쪽 높이 차를 엄격하게 관리해 탐색 경로를 짧게 유지하는 데 강함
- Red-Black 트리는 색상 규칙으로 균형을 완화해 유지하므로 AVL보다 회전 횟수가 적어 갱신 부담이 비교적 낮음
- B-Tree는 한 노드에 여러 키와 자식 포인터를 담아 트리 높이 자체를 낮추므로 디스크 페이지 접근 수를 줄이는 데 유리함
- 세 구조는 모두 균형을 유지하지만, 메모리 탐색 지연을 줄일지 디스크 I/O를 줄일지에 따라 적합한 선택이 달라짐

## Ⅲ. 종류 및 비교

- **AVL 트리**: 높이 차를 엄격히 제한해 탐색 경로를 짧게 유지하므로 조회가 많은 메모리 구조에 잘 맞음
- **Red-Black 트리**: 완화된 균형 규칙으로 삽입과 삭제 시 재조정 횟수를 줄여 갱신이 잦은 균형 검색 구조에 적합함
- **B-Tree**: 한 노드에 여러 키를 저장해 한 번의 페이지 읽기에서 더 많은 분기 정보를 얻으므로 디스크 인덱스에 적합함

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree |
|:---|:---|:---|:---|
| 균형을 맞추는 방식 | 높이 차를 엄격히 제한해 트리 높이를 직접 제어함 | 색상 규칙으로 불균형을 완화해 갱신 비용을 줄임 | 노드의 키 수와 자식 수를 조정해 높이를 낮게 유지함 |
| 강한 장점 | 탐색 경로가 짧아 조회 지연시간을 줄이기 좋음 | 삽입과 삭제 때 회전과 재색칠 부담이 비교적 작음 | 한 번의 페이지 접근으로 더 많은 키를 비교해 페이지 읽기 수를 줄임 |
| 주 저장 환경 | 메모리 안에서 빠른 조회가 필요한 구조에 적합함 | 메모리 안에서 조회와 갱신을 함께 처리하는 구조에 적합함 | 디스크나 페이지 캐시를 사용하는 인덱스 구조에 적합함 |
| 대표 적용 | 조회 중심 색인, 메모리 테이블에 많이 씀 | 표준 라이브러리 맵, 커널 내부 자료구조에 많이 씀 | 데이터베이스 인덱스, 파일 시스템 메타데이터에 많이 씀 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키와 자식 포인터 | 키는 어느 방향으로 내려갈지 판단하는 비교 기준이며, 자식 포인터는 그 판단 결과에 따라 다음 노드로 이동하게 함 |
| 균형 규칙 | AVL의 높이 차, Red-Black의 색상 제약, B-Tree의 차수와 채움률처럼 트리가 한쪽으로 늘어지지 않게 묶어 두는 기준임 |
| 재구성 연산 | 삽입과 삭제 뒤 균형이 깨지면 회전, 재색칠, 분할, 병합을 수행해 다시 허용 범위 안으로 되돌리는 연산임 |
| 노드 크기 | 한 노드에 담는 키와 포인터 수를 뜻하며, B-Tree에서는 디스크 페이지 크기와 맞아야 불필요한 페이지 낭비가 줄어듦 |

```text
+---------+     +-------------+     +-------------+
| 루트 노드  | --> | 자식 포인터들   | --> | 말단 탐색 경로  |
+---------+     +-------------+     +-------------+
      |
      v
+-------------+     +-------------+
| 균형 규칙    | --> | 회전/분할 복구  |
+-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 키비교   | --> | 하위이동 | --> | 삽입/삭제 | --> | 균형복구 |
+----------+     +----------+     +----------+     +----------+
```

1. **키비교**: 현재 노드의 키와 대상 키를 비교해 어느 자식 방향으로 내려갈지 정함
2. **하위이동**: 비교 결과에 따라 말단 노드나 삽입 지점까지 아래로 이동함
3. **삽입/삭제**: 새 키를 추가하거나 기존 키를 제거해 구조를 갱신함
4. **균형복구**: 높이 차, 색상 규칙, 차수 조건이 깨졌으면 회전, 재색칠, 분할, 병합으로 허용 범위를 회복함

## Ⅵ. 실무 적용 및 유의점

1. 표준 라이브러리 정렬 맵은 조회와 갱신이 모두 잦으므로 Red-Black 트리로 균형을 완화해 유지하고 탐색 시간과 삽입당 재조정 횟수로 확인함
2. 관계형 데이터베이스 인덱스는 이진 트리보다 B-Tree가 페이지 읽기 수를 줄이므로 조회당 페이지 접근 수와 인덱스 탐색 시간으로 확인함

## Ⅶ. 결론

트리 구조를 고를 때는 균형을 어떻게 유지하느냐보다 어떤 병목을 줄여야 하는지가 더 중요하므로, 메모리 조회에는 AVL이나 Red-Black을, 디스크 인덱스에는 B-Tree 계열을 맞춰 써야 함.
