## Ⅰ. 개요

- **정의**: 트리는 노드와 간선으로 이뤄진 계층 구조이며, 이진 탐색 트리(BST)는 좌<부모<우 규칙으로 정렬 상태를 유지하는 이진 트리임.
- **배경/필요성**: 삽입 순서가 한쪽으로 치우치면 BST 탐색이 최악 $O(N)$까지 나빠지므로, 삽입·삭제 때마다 스스로 균형을 복원해 $O(\log N)$을 보장하는 구조가 필요함. 디스크처럼 접근 단위가 큰 매체에서는 노드당 여러 키를 저장해 트리 높이 자체를 낮추는 구조가 추가로 요구됨.
- **출제 의도**: 균형 트리의 복원 메커니즘(회전 vs 분할·병합) 이해와, 메모리 상주형(AVL/Red-Black)·디스크 기반형(B-Tree/B+Tree)의 선택 판단 역량 확인.
- **답안 방향**: (1) BST가 편향될 수 있는 구조적 원인, (2) 회전·재색칠·분할·병합이라는 복원 수단의 차이, (3) 탐색:삽입 비율과 저장 매체 기준의 선택 판단 3축으로 전개.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 균형 트리의 구조·복원 원리 서술 | 균형인수/색 규칙/키 개수 상한이라는 판정 기준과 회전·분할·병합의 차이 | 정적 정렬 배열(004)의 $O(\log N)$ 탐색과 동적 균형 트리의 삽입·삭제 성능 혼동 |
| AVL·Red-Black·B-Tree 선택 판단 | 탐색:삽입 비율, 메모리/디스크 저장 위치 기준 | 특징만 나열하고 선택 기준·트레이드오프 누락 |

> 요약: 이 답안은 균형을 잃는 구조적 원인과, 그 균형을 되찾는 세 가지 복원 수단(회전·재색칠·분할)의 차이를 축으로 전개함.

## Ⅱ. 구조 및 구성요소

```text
BST 삽입/삭제 -> 균형 조건 위반 여부 판정
                 |
                 +-> AVL: 균형인수(좌우 높이 차) 확인 -> 1 초과 시 회전
                 +-> Red-Black: 색 규칙 위반 확인 -> 재색칠 우선, 부족 시 회전
                 +-> B-Tree/B+Tree: 노드 내 키 개수 확인 -> 상한 초과 시 분할, 하한 미달 시 병합
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| BST(이진 탐색 트리) | `좌 자식 < 부모 < 우 자식` 규칙으로 정렬 상태를 유지하는 기본 골격 | 정렬 규칙은 있으나 스스로 균형을 잡지는 못하는 구조 |
| 균형인수(Balance Factor) | 좌우 서브트리 높이 차를 계산해 불균형 여부를 판정하는 값 | 시소의 기울기 측정값 |
| AVL 트리 | 균형인수를 항상 1 이하로 유지하는 자가 균형 BST | 가장 엄격한 균형, 탐색 성능 최우선 |
| Red-Black 트리 | 5가지 색 규칙으로 높이 상한만 보장하는 느슨한 자가 균형 BST | Java TreeMap·Linux CFS 등 범용 컨테이너의 기반 |
| B-Tree | 한 노드에 여러 키를 저장해 높이를 낮춘 다진 탐색 트리 | 한 칸에 여러 책을 꽂아 층수를 줄인 서가 |
| B+Tree | B-Tree 변형, 데이터는 리프에만 두고 리프끼리 연결 리스트로 연결 | 범위 쿼리에 최적화된 RDBMS 인덱스 표준 |
| 회전(Rotation) | 부모-자식 포인터 관계를 재배치해 균형을 복원하는 $O(1)$ 연산 | 시소의 받침점을 옆으로 옮김 |
| 분할/병합(Split/Merge) | 노드의 키 개수가 상한 초과(분할) 또는 하한 미달(병합)일 때 노드 자체를 재구성하는 연산 | 서가 한 칸이 꽉 차면 옆 칸을 새로 만들어 나눠 꽂음 |

> 요약: BST가 정렬 규칙만 담당한다면, 균형인수·색 규칙·키 개수 상한이라는 판정 기준 위에서 회전 또는 분할·병합이 실제 균형 복원을 수행함.

## Ⅲ. 동작원리 및 흐름도

```text
삽입 위치 결정(BST 규칙) -> 조상 노드 검사 -> 불균형 발견 시 복원 연산 -> 루트까지 전파 확인
```

- 1단계 삽입 위치 탐색: `좌 < 부모 < 우` 규칙에 따라 리프 위치까지 내려가 새 노드를 삽입함.
- 2단계 조상 노드 검사: 삽입 경로를 따라 올라가며 각 조상의 균형 조건(AVL은 균형인수, Red-Black은 색 규칙, B-Tree는 노드 내 키 개수)을 확인함.
- 3단계 복원 연산 수행: AVL은 회전, Red-Black은 재색칠을 우선 시도하고 부족하면 최대 2회 회전, B-Tree는 상한 초과 시 분할·하한 미달 시 병합을 수행함.
- 4단계 전파 및 종료: 복원 결과가 상위 노드의 균형에 영향을 주면 루트까지 반복 확인하고, 더 이상 위반이 없으면 종료함.

> 요약: 삽입 경로를 따라 조상 노드의 균형 조건을 검사하고, 위반이 발견될 때만 회전·재색칠·분할 중 해당 트리의 복원 연산을 루트까지 전파함.

## Ⅳ. 특징

- 회전은 포인터 3개 내외 재배치만으로 끝나는 $O(1)$ 연산이며, 삽입 경로의 조상만 검사하므로 삽입 전체는 $O(\log N)$에 완료됨.
- AVL은 균형 기준이 가장 엄격해 탐색 높이가 낮지만, 삽입마다 필요한 회전 횟수가 Red-Black보다 늘어날 수 있음.
- Red-Black은 재색칠을 우선 적용해 회전 횟수를 상수 수준(최대 2~3회)으로 제한하므로, 삽입·삭제가 잦은 범용 컨테이너에 적합함.
- B-Tree/B+Tree는 노드당 여러 키를 저장해 트리 높이를 낮추고, 디스크 블록 단위 접근 횟수를 최소화하는 방향으로 설계됨.
- 정렬된 배열의 이진 탐색(004)은 탐색만 $O(\log N)$이고 삽입은 원소 이동 때문에 $O(N)$인 정적 구조인 반면, 균형 트리는 삽입·삭제까지 $O(\log N)$으로 유지하는 동적 구조라는 점이 핵심 차별점임.

> 요약: 균형 트리의 공통 강점은 삽입·삭제 후에도 탐색 성능이 유지된다는 것이며, 그 복원 비용을 어디에 지불하느냐(회전 횟수 vs 노드 재구성)가 유형별 특징을 가름.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | AVL 트리 | Red-Black 트리 | 선택 기준 |
|:---|:---|:---|:---|
| 균형 엄격도 | 좌우 높이 차 항상 1 이하 | 최장 경로가 최단 경로의 2배 이하만 보장 | 탐색 성능이 최우선이면 AVL |
| 복원 비용 | 삽입마다 최대 $O(\log N)$회 회전 | 재색칠 우선, 회전은 최대 2~3회 | 삽입·삭제가 잦으면 Red-Black |
| 적합 워크로드 | 읽기 위주 인메모리 인덱스 | 삽입·삭제가 빈번한 범용 컨테이너 | 탐색:삽입 비율로 판단 |

> 요약: 탐색이 압도적으로 많으면 AVL, 삽입·삭제가 잦은 범용 용도면 Red-Black이 유리하며, B-Tree/B+Tree는 저장 매체가 디스크일 때(4KB 블록 단위 I/O 최소화) 선택함.

**리스크·대응 (불릿):**
- 정렬된 키를 순서대로 연속 삽입하면 일반 BST는 편향돼 탐색이 $O(N)$으로 퇴화함 → 자가 균형 트리(AVL/Red-Black) 적용 (지표: 삽입 대비 회전·재색칠 발생 비율)
- 디스크 기반 인덱스에서 노드 크기를 디스크 블록 크기와 다르게 설계하면 불필요한 I/O가 늘어남 → 블록 크기에 맞춰 차수 $M$ 설계 (지표: 조회당 디스크 I/O 횟수)

**도입 후 점검 지표 (불릿):**
- 트리 높이: 실측 높이와 $\log_2 N$ 이론값의 괴리 여부
- 복원 연산 빈도: 삽입·삭제 대비 회전(AVL/RB) 또는 분할·병합(B-Tree) 발생 비율

## Ⅵ. 실무 적용 및 결론

1. 단기: 워크로드의 탐색:삽입 비율과 저장 위치(메모리/디스크)를 진단해 트리 유형 후보를 좁힘.
2. 중기: 디스크 기반 대용량 인덱스는 B+Tree, 인메모리 정렬 컨테이너는 AVL 또는 Red-Black을 적용하고 회전·분할 빈도를 측정함.
3. 장기: 트리 높이·복원 연산 빈도를 운영 지표로 편입하고, 워크로드 변화(읽기·쓰기 비율 역전 등) 시 트리 유형을 재검토함.

- 기술사적 판단: 탐색 위주 인메모리 구조는 AVL, 삽입·삭제가 잦은 범용 컨테이너는 Red-Black, 디스크 기반 대용량 인덱스는 B+Tree를 기본 선택지로 함.
- 기술사 제언: 자료구조 선택은 "정적 vs 동적"과 "메모리 vs 디스크"라는 두 축의 교차점에서 결정해야 하며, 균형 조건 위반 여부와 무관하게 획일적으로 한 트리를 고르지 않음.
