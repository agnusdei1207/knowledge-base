# 트리 구조 - B-Tree·AVL·Red-Black (Tree Data Structures)

## 1. 개요

- **정의/개념**: 트리는 노드와 간선의 부모-자식 관계로 계층 구조를 표현하고, 검색 트리는 키 순서로 탐색·삽입·삭제를 수행하는 비선형 자료구조이다.
- **배경/필요성**: 배열과 해시가 다루기 어려운 계층 표현, 정렬 순회, 범위 검색을 효율적으로 처리하기 위해 균형 유지가 가능한 트리 구조가 필요하다.

## 2. 특징 및 비교

| 구분 | B-Tree | AVL Tree | Red-Black Tree |
|---|---|---|---|
| 구조 | 다진 균형 검색 트리 | 엄격한 균형 이진 트리 | 완화된 균형 이진 트리 |
| 균형 기준 | 노드 키 수·자식 수 | 좌우 높이 차 | 색상 규칙 |
| 탐색 비용 | `O(log_m n)` | `O(log n)` | `O(log n)` |
| 갱신 비용 | 분할·병합 | 회전 빈번 | 회전 상대적으로 적음 |
| 주요 적용 | DB, 파일시스템 | 조회 중심 메모리 구조 | 범용 map/set |

B-Tree는 Binary Tree가 아니라 다진 검색 트리이며, 페이지 단위 I/O를 줄이기 위해 한 노드에 여러 키를 저장한다.

트리 선택은 정렬 순회·범위 질의 필요성, 저장 매체, 조회/갱신 비율, 균형 유지 비용, 동시성 제어 단위로 판단한다.

## 3. 구성요소/구조

```text
        Root
       /    \
  Subtree  Subtree
```

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Root | 탐색 시작 노드 | 전체 경로 시작점 |
| Key | 비교 기준 | 정렬 불변식 |
| Child Pointer | 하위 노드 연결 | 분기 구조 |
| Balance Info | 높이, 색상, 키 수 | 최악 성능 보장 |
| Leaf | 끝 노드 또는 데이터 접근 지점 | 범위 순회 |

트리 성능은 루트에서 리프까지의 높이에 좌우되며, 균형이 깨지면 탐색 비용이 `O(n)`까지 악화될 수 있다.

## 4. 문제점 및 개선방안

1. **편향 트리**
   - 일반 BST에 정렬된 키가 순서대로 삽입되면 한쪽으로 치우친다.
   - **개선방안**: AVL, Red-Black, B-Tree 같은 균형 트리를 사용한다.

2. **균형 유지 비용**
   - 삽입·삭제마다 회전, 색상 변경, 분할·병합이 발생할 수 있다.
   - **개선방안**: 조회/갱신 비율에 따라 AVL, RB, B-Tree를 선택한다.

3. **저장 매체 불일치**
   - 디스크 인덱스에 이진 트리를 쓰면 페이지 I/O가 증가한다.
   - **개선방안**: 디스크·DB 인덱스는 B-Tree/B+Tree처럼 페이지 단위 구조를 적용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 데이터베이스 인덱스 | B+Tree로 범위 질의와 정렬 출력 지원 | 트리 높이, 페이지 읽기 수 |
| 메모리 내 map/set | Red-Black Tree로 정렬 순회와 로그 시간 갱신 제공 | 조회·삽입 지연 |
| 파일시스템 | B-Tree 계열로 디렉터리·블록 위치 관리 | I/O 횟수, 탐색 시간 |

## 6. 결론

트리 구조는 계층 표현과 정렬 기반 탐색을 제공하는 핵심 자료구조이다. B-Tree·AVL·Red-Black Tree는 모두 로그 시간 탐색을 목표로 하지만, 저장 매체, 범위 질의, 조회/갱신 비율, 균형 유지 비용에 따라 선택 기준이 달라진다.
