# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 노드들이 부모-자식 관계의 계층형으로 연결되어 탐색 성능을 O(log N)으로 보장하는 비선형 자료구조
- **왜 필요한가**: 배열은 검색이 느리고(비정렬) 삽입/삭제가 끔찍하다(O(N)). 연결 리스트는 삽입/삭제는 유연하지만 탐색이 끔찍하다. 이 둘의 장점만 취해 "고속 검색 + 유연한 삽입/삭제"를 달성하기 위해 발명되었다.
- **핵심 직관**: 폴더 경로 구조나 가계도를 생각하면 쉽다. 무조건 위에서 아래로(루트->리프) 가지를 치며 절반씩 범위를 줄여나간다.

## 깊이 이해
- **배경·문제의식**: 기본 이진 탐색 트리(BST)는 데이터가 오름차순으로 계속 들어오면 한쪽으로만 가지가 뻗어 사실상 연결 리스트가 되어 탐색 시간이 O(N)으로 폭락한다(편향 트리).
- **작동 원리 (균형 유지)**: 
  - **AVL 트리**: 양쪽 서브트리 높이 차이가 1을 넘지 않도록 깐깐하게 회전(Rotation)하여 균형을 맞춘다. 읽기는 빠르나 쓰기(회전) 오버헤드가 크다.
  - **Red-Black 트리**: 노드에 색깔(Red/Black) 규칙을 주어 대략적인 균형을 맞춘다. 삽입/삭제가 AVL보다 유연해 언어 내장 Map 구현에 쓰인다.
  - **B-Tree**: 이진 트리 한계를 넘어 하나의 노드가 여러 자식(블록)을 가진다. 디스크 I/O 횟수를 극적으로 줄여 RDBMS 인덱스 표준이 되었다.
- **비유**: 
  - 편향 트리: 결재 서류가 사원->대리->과장->부장 1열로 올라가 결재 병목.
  - 균형 트리: 피라미드 조직도처럼 임원 1명 산하에 부서장 2명, 산하에 팀장 4명으로 분산해 탐색 최적화.
- **흔한 오해·주의점**: 트리가 무조건 O(log N)을 보장하는 것이 아니다. "균형 유지(Balancing) 알고리즘"이 탑재된 트리(AVL, Red-Black, B-Tree)만이 최악의 경우에도 O(log N)을 방어한다.

## 연결 개념
- 이진 탐색 (Binary Search)
- RDBMS 인덱스 구조 (B-Tree, B+Tree)
- 분산 데이터베이스 구조

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 탐색 공간을 매 노드마다 하위 분기 수로 분할하여 최악 O(log N) 조회·삽입을 달성하는 계층적 자료구조이다.
> 2. **가치**: 데이터가 한쪽으로 쏠리는 편향 트리 발생을 알고리즘적으로 방어하여 인프라의 응답 지연 한계(SLA)를 억제한다.
> 3. **판단 포인트**: 메인 메모리 구조(RAM)에서는 캐시 제어 유연성을 위한 Red-Black 트리를, 블록 단위 디스크 I/O가 발생하는 RDBMS 인덱스에는 B-Tree 계열을 적용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 편향 트리 문제점 및 자가 균형 유지 원리 확인 | 균형 인수(AVL), 색상 규칙(Red-Black), 분할 병합(B-Tree) | 세 트리의 이름만 나열하고 회전/분할의 구조적 방어 로직 누락 |
| 매체(Memory vs Disk) 특성에 따른 자료구조 선택 | B-Tree가 디스크 친화적인 이유 (노드 단위와 블록 매핑) | "B-Tree가 무조건 제일 좋다"며 메모리 환경 특성 무시 |

> 요약: 트리 구조 설계는 탐색 속도 방어를 위한 균형 비용 지불과, 저장 매체(RAM vs Disk)의 물리적 특성 결합의 산물이다.

## Ⅰ. 개요 및 필요성

- 정의: 이진 탐색의 경직성을 극복하고 탐색 공간을 O(log N)으로 유지하기 위해 계층적으로 노드를 연결한 균형 보장 자료구조
- 배경: 단순 이진 탐색 트리는 정렬된 데이터 삽입 시 연결 리스트화 되어 O(N)으로 전락하는 편향 취약점 내재
- 필요성: 시스템 인메모리 정렬 구조 유지 및 RDBMS 대용량 스토리지 인덱싱에서 안정적 지연시간 확보를 위해 자가 균형 메커니즘 필수

---

## Ⅱ. 3대 주요 트리 구조 및 방어 기전

```text
[요청] -> 균형 알고리즘 -> 회전(Rotation) / 색상 변경 / 노드 분할(Split) -> 균형 유지 트리 보장
```

| 트리 구조 | 자가 균형 메커니즘 | 특이사항 |
|:---|:---|:---|
| AVL Tree | 깐깐한 균형 인수(Balance Factor) 통제 | 좌우 높이 차를 항상 1 이하로 억제해 탐색 속도 극대화 |
| Red-Black Tree | 노드 색상(Red/Black) 5대 규칙 적용 통제 | 루트-리프까지 Black 노드 개수 일치 보장 (회전 감소) |
| B-Tree | 다원 탐색 및 블록(페이지) 단위 노드 구성 | 하나의 노드에 여러 키를 담아 트리 높이를 극적으로 단축 |

> 요약: AVL은 탐색 지향, Red-Black은 밸런싱 비용 저감 지향, B-Tree는 디스크 접근 횟수 최소화를 위해 설계되었다.

---

## Ⅲ. B-Tree 디스크 최적화 원리 및 분할 흐름도

```text
레코드 삽입 -> 노드 허용치 검사 -> 오버플로우 발생 시 노드 Split(분할) -> 중간값 부모 노드로 승격
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 타겟 노드 탐색 | 루트에서 하향 탐색하여 리프(Leaf) 노드 위치 확정 |
| 2 | 데이터 삽입 검증 | 타겟 노드 공간이 최대치 미만이면 삽입 후 종료 |
| 3 | 초과 분할 (Split) | 공간 초과 시 노드를 두 개로 쪼개고 중앙값을 부모 노드로 승격 |
| 4 | 연쇄 상승 (Cascade) | 부모 노드 초과 시 루트 방향으로 분할 반복 및 트리 높이 증가 |

> 요약: B-Tree 계열은 데이터가 위(Root 방향)로 밀려 올라가는 상향 증식 구조를 가져 전체 트리의 잎 깊이가 항상 일정하다.

## Ⅳ. 심화 비교 및 매체 특성 적용 판단

| 비교 축 | Red-Black Tree | B-Tree / B+Tree | 선택 기준 |
|:---|:---|:---|:---|
| 물리 매체 | Main Memory (RAM) 캐시 지향 | Disk / SSD 블록 저장소 지향 | 접근 매체의 I/O 지연 비용 폭 |
| 노드 크기 | 고정된 작은 객체 크기 (2 pointers) | 디스크 블록 크기 맵핑 (예: 8KB) | 캐시 라인 vs 페이지 사이즈 적합성 |
| 트리의 깊이 | 이진 분할로 비교적 깊음 | 다원 분할로 극도로 얕음 | 랜덤 I/O 횟수 임계치 여부 |
| 범위 검색 | 중위 순회를 통해 순차 획득 | B+Tree 리프 간 Linked List로 압도적 | 부등호 및 BETWEEN 쿼리 빈도 |

> 요약: RAM은 포인터 추적 지연이 작아 Red-Black이 유리하지만, 디스크는 헤드 이동 지연이 크므로 트리를 납작하게 만들어(B-Tree) 읽기 횟수를 줄인다.

| 리스크 | 발생 원인 | 대응 기법 | 확인 지표 |
|:---|:---|:---|:---|
| 인덱스 파편화 | 잦은 데이터 삭제/변경으로 노드 병합/분할 빈발 | 트리 Re-build (OPTIMIZE TABLE) 주기적 수행 | 페이지 단편화율 |
| 캐시 락 경합 | 트리 순회 시 글로벌 락 점유 문제 발생 | 노드/페이지 단위 파인 그레인(Fine-grain) 락 분산 | 락 경합 대기 시간 |

> 요약: 트리 구조는 갱신 오버헤드를 수반하므로 대량 데이터 삽입 시 인덱스를 비활성화 후 일괄 빌드하는 것이 표준이다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 클러스터 인덱스 설계: MySQL InnoDB 엔진에 B+Tree를 적용, 데이터 레코드와 인덱스 리프 노드를 묶어 순차 I/O로 최적화
2. 표준 라이브러리 엔진: Java의 TreeMap, TreeSet 내부 구조에 Red-Black 트리를 채택하여 악의적 삽입 공격 시에도 O(log N) 서비스 보장
3. 리눅스 스케줄러(CFS) 구현: 운영체제 완전 공정 스케줄러에서 실행 시간을 기준으로 Red-Black 트리를 구성해 다음 타겟을 즉시 선출

**결론 (2줄):**
- 기술사 판단: 트리는 탐색 고속화와 균형 유지 오버헤드 간의 타협이며, 저장 매체의 물리적 접근 비용 차이가 적용 경계를 결정한다.
- 향후 방향: 읽기/쓰기 비율이 치우치는 빅데이터 쓰기 환경에서는 B-Tree를 넘어 LSM-Tree(Log-Structured Merge Tree)가 스토리지 표준으로 채택되고 있다.
