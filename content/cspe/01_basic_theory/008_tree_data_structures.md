# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 트리는 노드들이 부모-자식 관계로 연결되어 계층(Hierarchy)을 이루는 **비선형 자료구조**로, 그중 각 노드가 자식을 최대 2개까지만 갖는 것을 이진 탐색 트리(BST), 자식 개수 편차를 스스로 교정하는 것을 균형 이진 탐색 트리(AVL·Red-Black), 자식을 여러 개 가질 수 있는 것을 B-Tree라 부른다.
- **왜 필요한가**: 배열은 조회는 O(1)이지만 삽입·삭제가 O(N)이고, 연결 리스트(006)는 그 반대다. 트리는 데이터를 정렬된 계층 구조로 배치해 조회·삽입·삭제를 모두 O(log N)에 가깝게 만들어 두 자료구조의 장점을 동시에 취하려는 시도다.
- **핵심 직관**: 스무고개 게임이다. 매 질문(노드 비교)마다 남은 탐색 범위가 절반(또는 1/n)으로 줄어들어, 전체를 하나씩 훑지 않고도 목표에 빠르게 도달한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 비선형 자료구조 | 가지치기 형태로 연결되는 자료구조 | 나뭇가지, 가계도 |
| 계층 구조(Hierarchy) | 상위-하위 관계가 있는 구조 | 회사 조직도 |
| 편향 트리(Skewed) | 한쪽으로만 가지가 뻗어 연결 리스트처럼 된 상태 | 외줄로 늘어선 도미노 |
| 회전(Rotation) | 균형을 맞추기 위해 노드 관계를 재배치하는 연산 | 시소 균형 맞추기 |
| B-Tree 분할(Split) | 노드가 꽉 찼을 때 둘로 쪼개고 중앙값을 부모로 올리는 연산 | 서랍 정리 및 목록 갱신 |

## 깊이 이해
- **이진 탐색 트리가 편향되는 이유**: BST는 "왼쪽엔 작은 값, 오른쪽엔 큰 값"이라는 규칙을 갖는다. 이미 정렬된 데이터가 순서대로 들어오면 한쪽으로만 치우쳐 높이가 N이 되어 탐색이 O(N)으로 저하된다. 이를 방지하기 위해 자가 균형 메커니즘이 필요하다.
- **AVL 트리의 엄격한 균형**: 왼쪽과 오른쪽 서브트리의 높이 차이(균형 인수)를 항상 1 이하로 엄격하게 맞춘다. 탐색은 매우 빠르지만 데이터 삽입/삭제 시 잦은 회전 연산이 발생한다.
- **Red-Black 트리의 느슨한 균형**: 노드에 색상(Red/Black)을 부여하여 최대 높이가 최소 높이의 2배를 넘지 않게 조절한다. AVL보다 회전이 적어 쓰기 성능이 우수하며 범용 라이브러리 표준으로 채택된다.
- **B-Tree의 디스크 최적화**: 디스크 접근 비용(I/O 지연)을 줄이기 위해 노드 하나에 수백 개의 데이터를 담아(디스크 블록 크기에 맞춤) 트리의 전체 높이를 극단적으로 낮춘 구조다.

## 연결 개념
- **006 연결 리스트**: 편향 트리는 사실상 연결 리스트로 퇴화한 상태다.
- **009 이진트리 순회**: 트리에 저장된 데이터를 훑어보거나 정렬 추출하는 기법이다.
- **RDBMS 인덱스 구조**: B-Tree 및 B+Tree가 데이터베이스 인덱스의 표준이다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 탐색 공간을 매 노드마다 하위 분기 수로 분할하여 최악의 경우에도 O(log N) 조회·삽입을 달성하는 계층적 균형 자료구조이다.
> 2. **가치**: 데이터가 한쪽으로 쏠리는 편향 트리 발생을 알고리즘적으로 방어하여 시스템 인프라의 응답 지연(SLA) 한계를 억제한다.
> 3. **판단 포인트**: 메인 메모리 구조(RAM)에서는 캐시 유연성을 위한 Red-Black 트리를, 블록 단위 디스크 I/O 환경인 RDBMS에서는 B-Tree 계열을 적용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 편향 트리 한계와 방어 기전 확인 | 균형 인수(AVL), 색상 규칙(Red-Black), 노드 분할(B-Tree) | 이름만 나열하고 회전/분할 구조적 로직 누락 |
| 매체별 자료구조 선택 기준 | B-Tree가 디스크 I/O 횟수를 최소화하는 수리적 근거 | 매체 특성(RAM vs Disk)을 무시한 범용 트리 추천 |

> 요약: 트리 구조 설계는 탐색 속도 방어를 위한 균형 재조정 비용 지불과, 저장 매체의 물리적 단위 맵핑의 산물이다.

## Ⅰ. 개요 및 필요성

- 개요: 이진 탐색의 경직성을 극복하고 탐색 공간을 균일하게 분할하기 위해 노드를 계층적으로 연결 및 재조정하는 자가 균형 구조
- 배경: 단순 이진 탐색 트리는 정렬된 데이터 삽입 시 한쪽으로 쏠려 O(N) 탐색 시간으로 전락하는 편향 취약점 내재
- 필요성: 시스템 인메모리 정렬 구조 유지 및 RDBMS 대용량 스토리지 인덱싱에서 안정적 쿼리 응답 시간을 확보하기 위해 자가 균형 메커니즘 필수

---

## Ⅱ. 3대 주요 트리 구조 방어 기전

```text
[검색/삽입 요청] -> 균형 상태 위반 탐지 -> 회전(Rotation)/색상 반전/노드 분할(Split) 연산 -> O(log N) 높이 재확보
```

| 트리 구조 | 자가 균형 메커니즘 | 특이사항 |
|:---|:---|:---|
| AVL Tree | 깐깐한 균형 인수(Balance Factor) 통제 | 좌우 서브트리 높이 차를 1 이하로 억제해 탐색 속도 극대화 |
| Red-Black Tree | 5대 노드 색상(Red/Black) 규칙 통제 | 루트부터 리프까지 Black 노드 수를 일치시켜 회전 오버헤드 최소화 |
| B-Tree | 다원 탐색 및 블록(페이지) 단위 병합/분할 | 1개 노드에 1개 블록 크기만큼 키를 담아 전체 트리 높이 대폭 축소 |

> 요약: AVL은 탐색 지향, Red-Black은 밸런싱 비용 저감 지향, B-Tree는 디스크 블록 접근 횟수 최소화를 위해 최적화되었다.

---

## Ⅲ. B-Tree 분할(Split) 동작 흐름도

```text
레코드 삽입 요청 -> 단말 노드 허용치 검사 -> 오버플로우 초과 시 노드 분할(Split) 발생 -> 중간값 부모 노드로 상향 승격
```

- 1단계 [타겟 탐색]: 루트 노드에서 하향 분기 탐색하여 리프(Leaf) 노드 위치 확정
- 2단계 [공간 검증]: 타겟 노드 공간이 블록 할당 최대치 미만이면 삽입 후 즉시 종료
- 3단계 [노드 분할]: 데이터 한계 초과 시 공간을 반으로 분할하고 중앙값을 부모로 승격
- 4단계 [연쇄 상승]: 부모 노드 연속 초과 시 루트 방향으로 연쇄 분할 발생 및 전체 트리 높이 증가

> 요약: B-Tree 계열은 데이터가 아래에서 위(Root)로 밀려 올라가는 상향 증식 구조를 지녀 모든 리프의 깊이가 동일하다.

---

## Ⅳ. 인메모리 트리 구조 특징 비교

| 구분 | AVL Tree | Red-Black Tree | 판단 포인트 |
|:---|:---|:---|:---|
| 균형 엄격도 | 좌우 높이차 최대 1로 엄격 고정 | 최대 높이가 최소 높이의 2배 이내 통제 | 탐색 허용 지연 한계 |
| 재조정 비용 | 삽입/삭제 시 지속적인 연쇄 회전 연산 강제 | 회전 최소화 및 색상 갱신으로 교정 처리 | 쓰기(Write) 갱신 빈도 |
| 적용 사례 | 읽기 집약적 고속 인메모리 인덱스 | 범용 STL 컨테이너(Map) 및 OS 스케줄러 | 조회 대비 데이터 변경 비율 |

> 요약: AVL 트리는 빠른 탐색을 위해 높은 갱신 비용을 치르며, Red-Black 트리는 느슨한 균형을 통해 쓰기 오버헤드를 경감시킨다.

## Ⅴ. 심화 비교 및 매체 특성 적용 판단

| 비교 축 | Red-Black Tree | B-Tree / B+Tree | 선택 기준 |
|:---|:---|:---|:---|
| 저장 매체 | Main Memory (RAM) 기반 최적화 | Disk / SSD 블록 기반 영구 저장소 최적화 | 시스템 매체 접근 지연 단위 |
| 노드 크기 | 포인터 2개의 고정된 작은 객체 단위 | 디스크 블록 페이지 사이즈(예: 8KB) 매핑 | 하드웨어 I/O 단위 적합성 |
| 범위 검색 | 중위 순회(In-order)로 순차 획득 연산 | B+Tree 리프 간 Linked List 선형 순차 스캔 | BETWEEN 쿼리 및 부등호 빈도 |

> 요약: RAM은 포인터 추적 오버헤드가 작아 Red-Black이 유리하지만, 디스크는 탐색 지연이 커 트리를 넓게 구성하는 B-Tree를 채택한다.

**리스크·대응:**
- 인덱스 파편화: 잦은 데이터 삭제/변경으로 B-Tree 노드 병합 빈발 및 낭비 발생 → 트리 전체 Re-build (OPTIMIZE TABLE) 주기적 수행 (지표: 인덱스 페이지 단편화율)
- 캐시 락 경합 병목: 트리 구조 순회 시 글로벌 락 점유로 동시성 저하 → 노드 단위 파인 그레인(Fine-grain) 락 모델 분산 설계 (지표: 락 경합 대기 시간)
- 잦은 밸런싱 지연: 대량의 초기 데이터 삽입 시 트리 회전/분할 급증 → 데이터 로드 시 인덱스 비활성화 후 일괄 빌드(Bulk Load) 적용 (지표: 인덱싱 처리 시간)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 클러스터 인덱스 구축: MySQL InnoDB에 B+Tree를 적용, 데이터 레코드와 인덱스 리프 노드를 함께 묶어 순차 I/O 성능 극대화
2. 리눅스 커널 프로세스 스케줄러(CFS): 완전 공정 스케줄러 내부에 실행 시간을 기준으로 Red-Black 트리를 구성해 차기 프로세스 O(log N) 추출
3. 컬렉션 프레임워크 표준 적용: Java의 TreeMap, TreeSet 내부 코어 엔진에 Red-Black 트리를 채택하여 악의적 삽입 공격에도 상수 시간 응답 방어

**결론 (2줄):**
- 기술사 판단: 트리 구조는 탐색 고속화와 균형 유지 오버헤드 간의 타협이며, 저장 매체의 물리적 접근 속도 차이가 구조 결정의 절대 경계가 된다.
- 향후 방향: 쓰기 집중형 빅데이터 환경에서는 B-Tree의 한계를 넘어 쓰기 앰플리피케이션을 줄인 LSM-Tree(Log-Structured Merge Tree)가 스토리지 표준으로 채택되고 있다.
