## Ⅰ. 개요
- **정의**: 노드 간 부모-자식 관계로 계층을 형성하며, 균형 유지 규칙을 적용해 탐색·삽입·삭제를 O(log n)으로 보장하는 비선형 자료구조
- **배경/필요성**: 선형 자료구조는 탐색 시 O(n)이 발생하므로, 계층적 분할을 통해 비교 횟수를 로그 수준으로 줄이는 구조가 요구됨
- **비유**: 사전 찾기 — 중간 페이지를 펼쳐 앞뒤를 절반씩 줄여가며 단어를 찾는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 균형 트리 간 구조·규칙 차이 | AVL(높이 균형), RB(색 규칙), B-Tree(다진 분기) | BST 편향 시 O(n) 퇴화를 반드시 언급할 것 |

> 요약: 균형 규칙으로 트리 높이를 O(log n)에 유지하여 탐색·삽입·삭제 성능을 보장하는 구조임

## Ⅱ. 구성요소
```text
           BST (기본)
            [30]
           /    \
        [20]    [40]
        /  \       \
     [10] [25]    [50]

  AVL: 모든 노드의 좌우 서브트리 높이 차 <= 1
  RB:  루트=Black, Red 노드의 자식=Black, 경로별 Black 수 동일
  B-Tree: 한 노드에 M-1개 키, M개 자식 -> 디스크 블록 단위 탐색
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| BST | 좌측 자식 < 부모 < 우측 자식 규칙을 따르는 이진 탐색 트리 | 정렬된 서류함 — 왼쪽은 작은 번호, 오른쪽은 큰 번호 |
| AVL Tree | 모든 노드의 좌우 서브트리 높이 차를 1 이하로 유지하며 회전으로 균형을 맞추는 트리 | 양팔 저울 — 한쪽이 기울면 추를 옮겨 균형 복원 |
| Red-Black Tree | 노드에 Red/Black 색을 부여하고 색 규칙으로 균형을 근사적으로 유지하는 트리 | 교통 신호등 — 색 규칙으로 흐름(균형)을 제어 |
| B-Tree | 한 노드에 복수 키를 저장하여 디스크 I/O 횟수를 최소화하는 다진 탐색 트리 | 서랍장 — 한 서랍에 여러 파일을 넣어 열기 횟수를 줄임 |
| 회전 연산 | AVL/RB에서 불균형 발생 시 노드 위치를 재배치하는 LL/RR/LR/RL 연산 | 시소 균형 맞추기 — 한쪽이 무거우면 지렛대를 이동 |

> 요약: BST를 기반으로 AVL(높이), RB(색), B-Tree(다진 분기) 규칙으로 균형을 유지함

## Ⅲ. 절차
```text
  키 비교/탐색        삽입 위치 결정      노드 삽입           균형 복원
  (루트부터 분기)    (리프 도달)         (노드 생성)         (회전/분할)
       |                 |                  |                  |
       +---좌우 비교----->+---리프 탐색------>+---키 저장-------->+
     O(log n) 비교     BST 규칙 적용      새 노드 연결      AVL회전/RB색변경/B분할
```
- 1단계: 루트에서 시작하여 키 값을 비교하며 좌측·우측 서브트리로 분기함
- 2단계: BST 규칙에 따라 리프 노드에 도달하여 삽입 위치를 결정함
- 3단계: 새 노드를 생성하고 해당 위치에 연결함
- 4단계: 균형 규칙 위반 시 AVL은 회전, RB는 색 변경+회전, B-Tree는 노드 분할을 수행하여 균형을 복원함

> 요약: 키 비교 → 위치 결정 → 삽입 → 균형 복원의 4단계로 O(log n) 성능을 유지함

## Ⅳ. 문제점
- BST 편향: 정렬된 데이터 삽입 시 한쪽으로 치우쳐 높이가 n이 되어 O(n) 퇴화 — 균형 트리 없이 사용 시 탐색 성능 보장 불가
- AVL 회전 비용: 삽입·삭제마다 높이 재계산 및 최대 O(log n) 회전 수행 — 삽입·삭제 빈도가 높은 경우 오버헤드 증가
- B-Tree 구현 복잡도: 노드 분할·병합·재분배 로직이 복잡하여 인메모리 용도에서는 구현 대비 이점이 낮음

> 요약: BST 편향 퇴화, AVL 회전 오버헤드, B-Tree 구현 복잡도가 주요 한계임

## Ⅴ. 개선방안
1. 단기: 정렬 데이터 삽입 시 AVL 또는 RB 트리를 적용하여 편향 퇴화를 방지
2. 중기: 삽입·삭제가 빈번한 경우 RB 트리(AVL 대비 회전 횟수 절감)를 선택하여 갱신 비용 절감
3. 장기: 디스크 기반 대용량 데이터에 B+Tree(리프 연결 리스트)를 적용하여 범위 탐색과 I/O 효율을 동시 확보

> 요약: 균형 트리 적용 → RB 트리 선택 → B+Tree 확장으로 단계적 성능·효율을 확보함

## Ⅵ. 전망
- 발전 방향: LSM-Tree, Fractal Tree 등 쓰기 최적화 트리 구조가 대규모 저장 시스템에서 확산됨
- 기술사적 판단: DBMS 인덱스, 파일시스템, 메모리 관리 등 시스템 전반에서 트리 선택이 성능을 좌우함
- 기술사 제언: 워크로드 특성(읽기/쓰기 비율, 디스크/메모리)에 따른 트리 구조 선정 기준을 수립할 필요
