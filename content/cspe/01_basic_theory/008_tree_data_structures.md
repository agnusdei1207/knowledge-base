## 미리 알고가기

- 자가 균형 트리(Self-Balancing Tree): 삽입·삭제 후 높이를 조정해 탐색 경로를 $O(\log n)$ 수준으로 유지하는 트리임
- 회전(Rotation): 부모·자식 위치를 바꿔 이진 탐색 트리 순서를 보존하면서 높이 편차를 줄이는 연산임
- 페이지(Page): DB·파일 시스템 인덱스에서 디스크가 한 번에 읽는 최소 블록 단위임
- 균형 인자($BF$): 왼쪽 서브트리 높이와 오른쪽 서브트리 높이의 차이임
- 편향 트리(Skewed Tree): 노드가 한쪽으로 쏠려 탐색 경로가 $O(n)$으로 퇴화한 트리임

## Ⅰ. 개요

- **정의/개념**: 트리 구조는 부모-자식 관계로 데이터를 계층화하고, AVL·Red-Black·B-Tree는 키 탐색 경로를 균형 규칙으로 제한하는 탐색 트리임
- **배경/필요성**: 단순 이진 탐색 트리는 정렬 입력에서 한쪽으로 쏠리므로 조회·갱신 지연을 예측하려면 균형 유지 방식이 필요함

## Ⅱ. 특징

- 키 비교가 현재 노드의 왼쪽·오른쪽 또는 다분기 자식 중 이동 방향을 결정함
- 균형 조건은 트리 높이를 제한해 최악 탐색 경로를 통제함
- AVL·Red-Black은 인메모리 갱신 비용과 조회 경로 길이의 균형점이 다름
- B-Tree는 한 노드에 여러 키를 담아 디스크 페이지 읽기 횟수를 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree (B+/B*) |
|:---|:---|:---|:---|
| **균형 원리** | 균형 인자 절댓값 1 이하 | 색상(R/B) 규칙 기반 완화 균형 | 노드 내 키/자식 개수 범위 유지 |
| **탐색 성능** | 경로가 가장 짧음 | AVL보다 완화된 높이 | 디스크 I/O 횟수 감소 |
| **갱신 비용** | 회전 빈도 높음 | 재색칠 중심 조정 | 분할·병합 비용 발생 |
| **주요 활용** | 조회 중심 인메모리 검색 | Java TreeMap, 리눅스 커널 | DB 인덱스, 파일 시스템 |

> 요약: 조회 중심은 AVL, 갱신 중심은 Red-Black, 외부 저장소 인덱스는 B-Tree가 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 루트 노드 | 모든 탐색이 시작되는 최상단 노드이며 높이 변화가 전체 경로 길이를 좌우함 |
| 분기 키($Key$) | 값의 대소나 범위를 비교해 다음 자식 방향을 정하는 기준값임 |
| 균형 메타정보 | 균형 인자, 색상, 키 개수처럼 재구성 여부를 판단하는 상태값임 |
| 자식 포인터 | 하위 노드의 메모리 주소 또는 디스크 블록 주소를 가리킴 |
| 재구성 연산 | 회전, 재색칠, 분할·병합으로 탐색 순서와 균형 조건을 동시에 보존함 |

```text
[ 트리 재구성 - 회전 예시 ]
      (A)                         (B)
     /   \       Right Rot       /   \
   (B)   (C)   ----------->    (D)   (A)
   / \                               / \
 (D) (E)                           (E) (C)

[ B-Tree 노드 예시 ]
+-------------------+      +-----------------+
| K1 | K2 | K3      | ---> | P0 P1 P2 P3     |
+-------------------+      +-----------------+
```

> 요약: 균형 트리는 재구성 규칙으로 높이를 제한하고 B-Tree는 페이지 단위 접근을 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 탐색 및 갱신 | --> | 균형 상태 확인 | --> | 재구성 연산  | --> | 정합성 검증  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **탐색 및 갱신**: 키 비교로 삽입 위치나 삭제 대상을 확정함
2. **균형 확인**: 갱신 지점에서 루트 방향으로 균형 조건 위반을 점검함
3. **재구성 수행**: 회전, 재색칠, 분할·병합으로 조건을 회복함
4. **정합성 검증**: 탐색 순서와 높이·색상·키 개수 조건을 확인함

> 요약: 트리 갱신은 탐색 순서를 보존하면서 높이·색상·키 개수 조건을 회복해야 함.

## Ⅵ. 실무 적용 및 유의점

1. 갱신 많은 인메모리 색인은 Red-Black을 우선 검토하고 p95 갱신 지연·회전/재색칠 횟수로 확인함
2. DB 인덱스는 B-Tree 계열로 페이지 I/O를 줄이고 트리 높이·페이지 읽기·노드 분할 빈도로 확인함
