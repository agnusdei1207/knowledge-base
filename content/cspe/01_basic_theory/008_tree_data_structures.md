## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 트리(Tree)는 $N$개의 노드와 $N-1$개의 간선으로 구성되어 임의의 두 노드 사이 경로가 유일한 비순환 계층 자료구조임. 이 중 이진 탐색 트리(BST)는 좌측 자식 < 부모 < 우측 자식 규칙으로 정렬 상태를 유지하되, **삽입·삭제 시에도 스스로 균형을 복원**하여 탐색·삽입·삭제 모두를 $O(\log N)$으로 보장하는 것이 균형 트리(AVL·Red-Black·B-Tree)의 핵심임.
> 2. **가치**: 정렬된 배열의 이진 탐색(004 참조)은 탐색은 $O(\log N)$이나 삽입 시 $O(N)$ 시프트가 필요한 **정적 구조**임. 균형 트리는 삽입·삭제까지 $O(\log N)$으로 유지하는 **동적 구조**로 이 한계를 해결하며, DB 인덱스(B-Tree/B+Tree)·파일시스템·OS 스케줄러(Red-Black)의 뼈대를 이룸.
> 3. **융합**: 트리마다 균형을 되찾는 메커니즘이 다름 — AVL·Red-Black은 개별 노드 단위의 **회전(Rotation)**으로, B-Tree는 노드 내 키 재배치와 **분할·병합(Split/Merge)**으로 균형을 복원함. 이 메커니즘의 차이가 메모리 상주 자료구조(AVL/RB)와 디스크 기반 인덱스(B-Tree)의 선택 기준이 됨.

### 🔑 핵심 용어 정리

| 용어 | 정의 | 비유 / 부연 |
|:---|:---|:---|
| **이진 탐색 트리 (BST)** | 좌측 자식 < 부모 < 우측 자식 규칙을 만족하는 이진 트리 | 스무고개 — 매번 반씩 좁혀감 |
| **균형 인수 (Balance Factor)** | 좌우 서브트리 높이 차. AVL은 이 값이 1 초과 시 불균형으로 판정 | 시소의 기울기 측정값 |
| **AVL 트리** | 균형 인수를 항상 1 이하로 유지하는 자가 균형 BST | 가장 엄격한 균형 — 탐색이 최빠름 |
| **Red-Black 트리** | 5가지 색칠 규칙으로 높이 상한만 보장하는 느슨한 자가 균형 BST | Java TreeMap·C++ std::map·Linux CFS 기반 |
| **B-Tree** | 한 노드에 여러 키를 저장해 높이를 낮춘 다진 탐색 트리 | 도서관 서가 — 한 칸에 여러 책을 꽂아 층수를 줄임 |
| **B+Tree** | B-Tree 변형. 데이터는 리프에만 두고 리프끼리 연결 리스트로 연결 | RDBMS 인덱스의 사실상 표준 |
| **회전 (Rotation)** | 부모-자식 관계를 재배치해 균형을 복원하는 $O(1)$ 연산 | 시소의 중심축(받침점)을 옆으로 옮김 |
| **분할 / 병합 (Split / Merge)** | B-Tree에서 노드의 키 개수가 상한 초과(분할) 또는 하한 미만(병합)일 때 노드 자체를 재구성하는 연산 | 서가 한 칸이 꽉 차면 옆 칸을 새로 만들어 나눠 꽂음 |

## Ⅰ. 개요 및 필요성

- **개념**: 트리는 노드와 간선으로 구성된 계층 구조이며, 이 중 BST는 정렬 규칙을 만족하는 이진 트리임. 균형 트리는 삽입·삭제 후에도 높이를 $O(\log N)$ 수준으로 재조정하여 최악 성능을 보장함.
- **필요성**: 004(이진 탐색)의 정렬 배열은 탐색은 $O(\log N)$이지만 삽입은 원소 이동 때문에 $O(N)$이 걸리는 정적 구조임. 실무는 "정렬 상태를 유지하면서 삽입·삭제도 빠른" 동적 구조가 필요하며, 이 요구를 BST의 자가 균형 변형(AVL·Red-Black·B-Tree)이 충족함.
- **비유**: 편향(Skewed) BST는 한쪽으로만 자란 **대나무**여서 쓰러지기 쉽고, 균형 트리는 가지치기로 좌우 무게를 맞춘 **분재(盆栽)**임. B-Tree는 한 칸에 여러 책을 꽂아 층수를 줄인 **도서관 서가**임.
- **범위 한정**: 트리의 방문 순서(전위·중위·후위)는 009(이진트리 순회)에서 다루므로 본 파일은 반복하지 않고, 균형을 되찾는 메커니즘(회전·리밸런싱)에 집중함.
- **등장 배경 및 발전 과정**:
  - **1962년 — AVL 트리**: Adelson-Velsky와 Landis가 논문 "An algorithm for the organization of information"에서 최초의 자가 균형 BST를 발표함. 좌우 서브트리 높이 차(균형 인수)를 1 이하로 유지함.
  - **1972년 — Red-Black 트리의 원형과 B-Tree**: Bayer가 "Symmetric Binary B-Trees"에서 대칭 이진 B-트리를 발표함(이후 Red-Black 트리로 재명명됨). 같은 해 Bayer와 McCreight가 별도로 "Organization and Maintenance of Large Ordered Indices"에서 디스크 인덱스용 B-Tree를 발표함.
  - **1978년 — Red-Black 트리 정식화**: Guibas와 Sedgewick이 "A Dichromatic Framework for Balanced Trees"에서 색칠 규칙과 "Red-Black"이라는 이름을 도입해 현재 형태로 체계화함.

```text
+-----------------------------------------------------------------------+
|          균형 트리 vs 편향 트리 - 높이가 탐색 성능을 결정             |
+-----------------------------------------------------------------------+
|                                                                       |
|  [균형 BST, 높이 = log2 N]         [편향 BST, 높이 = N-1]            |
|                                                                       |
|          (8)                       (1)                               |
|         /   \                        \                               |
|       (4)   (12)                     (2)                            |
|       / \   / \                        \                             |
|     (2)(6)(10)(14)                     (3)                           |
|                                          \                            |
|  N=15, 높이=3                            (4)                         |
|  최대 비교 횟수: 4회                       ... (이하 순차 증가)       |
|  O(log 15) 근사 4                        N=15, 높이=14               |
|                                           최대 비교 횟수: 15회        |
|                                           O(N) - 연결 리스트와 동일   |
+-----------------------------------------------------------------------+
```

같은 15개 원소를 저장해도 균형 여부에 따라 최악 탐색 비교 횟수가 4회와 15회로 갈림. 편향 BST는 $1, 2, 3, \ldots$ 순서로 계속 삽입하면 발생하며, 이 경우 트리는 사실상 연결 리스트와 동일한 $O(N)$ 구조로 퇴화함. AVL·Red-Black·B-Tree는 이 퇴화를 막기 위해 삽입·삭제 시마다 균형 복원 절차를 실행함.

## Ⅱ. 아키텍처 및 핵심 원리

### 균형 트리 유형별 비교

| 트리 | 균형 기준 | 노드당 키 수 | 높이 상한 | 균형 복원 방식 |
|:---|:---|:---|:---|:---|
| **AVL 트리** | 좌우 높이 차 $\le 1$ | 1 | 약 $1.44 \log_2 N$ | 회전(엄격, 삽입마다 최대 $O(\log N)$회) |
| **Red-Black 트리** | 색칠 규칙 5가지 | 1 | 약 $2 \log_2 N$ | 재색칠 우선, 최대 2~3회 회전 |
| **B-Tree** | 모든 리프가 같은 깊이 | $M/2$ ~ $M$ | 약 $\log_{M/2} N$ | 노드 분할(Split)·병합(Merge) |
| **B+Tree** | B-Tree와 동일 + 리프 연결 | 내부: 키만, 리프: 데이터 | 약 $\log_{M/2} N$ | B-Tree와 동일 + 리프 연결 리스트 유지 |

> 요약: AVL/Red-Black은 노드 단위 회전으로, B-Tree/B+Tree는 노드 내부 재구성(분할·병합)으로 균형을 복원하며, 이 방식 차이가 메모리용(AVL/RB)과 디스크용(B-Tree) 선택 기준이 됨.

### 핵심 원리 — 회전(Rotation)과 분할(Split)

```text
+-----------------------------------------------------------------------+
|          AVL 트리 - 단일 회전(Single Rotation)으로 균형 복원          |
+-----------------------------------------------------------------------+
|                                                                       |
|  [삽입 전, 균형]        [삽입 후, 불균형]        [회전 후, 복원]      |
|                                                                       |
|       (10)                  (10)                    (5)              |
|       /                     /                       /  \            |
|     (5)                   (5)                     (3)  (10)         |
|                            /                       /                 |
|                          (3)                     (1)                 |
|                          /                                            |
|                        (1)  <- 삽입                                  |
|                                                                       |
|  노드 10 균형인수: 1-0=1(정상)   삽입 후: 3-0=3(불균형, 1 초과)      |
|  처리: 노드 10 기준 우회전(Right Rotation) 수행                       |
|  결과: 노드 5가 새 루트, 노드 10은 5의 우측 자식으로 이동             |
+-----------------------------------------------------------------------+
```

노드 1 삽입 후 노드 10의 균형 인수가 3으로 벌어져 불균형이 발생하면, 노드 10을 기준으로 우회전을 수행해 노드 5를 새 루트로 올림. 회전은 포인터 3개 변경만으로 완료되는 $O(1)$ 연산이며, 삽입 경로의 조상 노드만 확인하므로 삽입 전체는 $O(\log N)$에 끝남. 불균형 방향에 따라 LL(좌측-좌측, 단일 우회전)·RR(우측-우측, 단일 좌회전)·LR(좌측-우측, 좌회전 후 우회전)·RL(우측-좌측, 우회전 후 좌회전) 4가지 유형으로 나뉘며, LR·RL은 회전을 두 번 수행하는 이중 회전임.

Red-Black 트리는 삽입 시 규칙 위반이 생기면 회전보다 **재색칠(Recoloring)**을 우선 시도하고, 재색칠로 해결이 안 될 때만 최대 2회의 회전을 수행함. AVL보다 균형 기준이 느슨한 대신 삽입·삭제당 회전 횟수가 상수로 제한되어, 삽입·삭제가 잦은 범용 컨테이너(Java TreeMap 등)에 적합함.

B-Tree는 노드 단위로 균형을 유지함. 노드의 키 개수가 상한 $M$을 초과하면 중간 키를 부모로 승격시키고 노드를 둘로 나누는 **분할(Split)**을 수행하며, 삭제로 키 개수가 하한 $\lceil M/2 \rceil$ 미만이 되면 형제 노드에서 키를 빌리거나(Borrow) 그마저 불가능하면 인접 노드와 합치는 **병합(Merge)**을 수행함. 분할·병합은 트리의 높이를 한 번에 최대 1씩만 바꾸므로, B-Tree는 회전 없이도 모든 리프가 항상 같은 깊이를 유지하는 완전 균형 구조가 됨.

## Ⅲ. 비교 및 연결

### 비교 1: AVL 트리 vs Red-Black 트리

| 비교 항목 | AVL 트리 | Red-Black 트리 |
|:---|:---|:---|
| **균형 엄격도** | 엄격 (높이 차 $\le 1$) | 느슨 (최장 경로 $\le$ 최단 경로 $\times 2$) |
| **탐색 성능** | 더 빠름 (높이가 더 낮음) | 약간 느림 (높이 상한이 더 큼) |
| **삽입/삭제당 회전 수** | 최대 $O(\log N)$회 | 최대 2~3회 (상수) |
| **적합한 경우** | 탐색 빈도가 삽입보다 훨씬 높음 | 삽입·삭제가 빈번한 범용 컨테이너 |
| **대표 사용처** | 읽기 위주 인메모리 인덱스 | Java TreeMap, Linux CFS, C++ std::map |

> 요약: 탐색이 압도적으로 많으면 AVL, 삽입·삭제가 잦은 범용 용도면 Red-Black이 유리함 — 균형 엄격도와 삽입 비용의 트레이드오프임.

### 비교 2: B-Tree vs B+Tree

| 비교 항목 | B-Tree | B+Tree |
|:---|:---|:---|
| **데이터 저장 위치** | 내부 노드 + 리프 노드 | 리프 노드에만 |
| **내부 노드 내용** | 키 + 데이터 포인터 | 키(인덱스 역할)만 |
| **범위 쿼리** | 중위 순회 필요 | 리프 연결 리스트 순차 접근 |
| **동일 노드 크기 대비 팬아웃** | 데이터 포함으로 상대적으로 작음 | 키만 저장해 더 큼 → 높이 더 낮음 |
| **실무 표준** | 일반 파일시스템 인덱스 | RDBMS (MySQL InnoDB, PostgreSQL) |

> 요약: B+Tree는 리프 연결과 큰 팬아웃 덕분에 범위 쿼리와 디스크 I/O 효율에서 B-Tree보다 유리해 RDBMS 인덱스 표준으로 채택됨.

### 과목 융합 관점

- **데이터베이스**: InnoDB의 클러스터드 인덱스는 B+Tree이며 리프 노드에 실제 행 데이터가 저장됨. 세컨더리 인덱스의 리프에는 프라이머리 키가 저장되어, 세컨더리 인덱스 탐색 후 클러스터드 인덱스를 한 번 더 탐색함(더블 룩업).
- **운영체제**: Linux CFS(Completely Fair Scheduler)는 Red-Black 트리에 프로세스를 가상 실행 시간(vruntime) 순으로 저장하며, 가장 왼쪽(최소 vruntime) 노드를 $O(\log N)$에 선택함.
- **보안**: 머클 트리(Merkle Tree)는 해시를 리프에서 루트로 집계하는 이진 트리로, 블록체인에서 트랜잭션 무결성을 $O(\log N)$에 검증함.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **데이터베이스 인덱스 설계**: 1억 건 사용자 테이블에서 `id` 조회 시, 차수 $M=200$인 B+Tree 인덱스는 높이가 $\log_{100}(10^8) \approx 4$여서 최대 4회의 디스크 I/O로 행을 찾음. 인덱스가 없으면 풀 스캔으로 최악 $10^8$회 비교가 필요함.
2. **실시간 임베디드 시스템의 최악 성능 보장**: 장애물 목록처럼 안전이 걸린 데이터를 관리할 때 Red-Black 트리를 쓰면 삽입·삭제·탐색이 최악의 경우에도 $O(\log N)$으로 고정됨. 해시 테이블의 최악 $O(N)$ 충돌 상황이나 일반 BST의 편향 위험은 이런 환경에서 허용하기 어려움.

### 도입 체크리스트

- **기술적**: 순서 유지와 범위 쿼리가 필요한가 (필요 시 BST 계열), 디스크 기반 저장인가 (디스크면 B-Tree/B+Tree, 메모리면 AVL/Red-Black).
- **운영 및 보안적**: 최악 케이스 $O(\log N)$ 보장이 요구되는가, 정렬된 입력이 그대로 삽입되어 편향을 유발할 가능성이 있는가.

### 안티패턴

- **정렬된 데이터를 일반 BST에 순서대로 삽입**: $1, 2, \ldots, N$ 순서로 삽입하면 높이 $N$의 편향 트리가 되어 탐색이 $O(N)$으로 퇴화함. 자가 균형 트리를 쓰거나 삽입 전 순서를 섞어야 함.
- **메모리 상주 자료구조에 B-Tree 적용**: B-Tree는 디스크 블록(통상 4KB) 단위 I/O 최소화를 위해 노드 크기를 크게 설계한 구조임. 메모리에서는 캐시 라인(64바이트) 크기에 맞는 AVL/Red-Black이 더 유리함.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 편향 BST / 풀 스캔 | 균형 트리 적용 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | $O(N)$ 탐색, $N=1$억 시 최악 1억 회 비교 | $O(\log N)$, 최악 약 27회 비교 | 비교 횟수 약 **370만 배** 감소 |
| **정량** | B+Tree 미적용 풀 스캔 시 수만 회 디스크 I/O | 높이 4인 B+Tree 인덱스로 I/O 4회 | 디스크 I/O 대폭 감소 |
| **정성** | 삽입 순서에 따라 최악 성능 예측 불가 | 삽입·삭제 후에도 항상 $O(\log N)$ 보장 | 성능 예측 가능성 확보 |

> 요약: 균형 트리는 탐색 비교 횟수를 수백만 배 줄이고 디스크 I/O를 대폭 낮추며, 무엇보다 삽입 순서와 무관하게 항상 $O(\log N)$을 보장함.

### 미래 전망

- **LSM-Tree(Log-Structured Merge Tree)**: 쓰기 집약 워크로드에 최적화된 구조로 Cassandra·RocksDB·LevelDB의 핵심이며, B-Tree 대비 쓰기 증폭(Write Amplification)이 낮음.
- **학습 기반 인덱스(Learned Index)**: B-Tree의 내부 노드 탐색을 데이터 분포를 학습한 모델로 대체해 키 위치를 예측하는 연구가 진행 중임.

### 참고 표준

- **Adelson-Velsky, G.M. & Landis, E.M. (1962)**: "An algorithm for the organization of information" — AVL 트리 원논문
- **Bayer, R. & McCreight, E. (1972)**: "Organization and Maintenance of Large Ordered Indices" — B-Tree 원논문
- **Bayer, R. (1972)**: "Symmetric Binary B-Trees: Data Structure and Maintenance Algorithms" — Red-Black 트리의 원형
- **Guibas, L.J. & Sedgewick, R. (1978)**: "A Dichromatic Framework for Balanced Trees" — Red-Black 트리의 색칠 규칙 및 명명 정식화

트리는 배열의 정적 탐색과 연결 리스트의 순서 없는 확장이 각각 놓친 지점, 즉 "정렬 상태를 유지하면서 삽입·삭제도 빠르게"라는 요구를 충족시키는 자료구조임. 이 요구를 회전으로 풀 것인가(AVL/Red-Black) 노드 분할로 풀 것인가(B-Tree)의 선택이 메모리 구조와 디스크 구조를 가르는 기준이 됨.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| 이진 탐색 (004) | 정렬 배열의 정적 탐색 — 트리는 이를 동적 삽입·삭제 가능한 구조로 확장함. |
| 이진트리 순회 (009) | 트리를 방문하는 순서(전위·중위·후위)를 다룸 — 균형 유지와는 별개 주제. |

| 해시 테이블 | $O(1)$ 조회 vs $O(\log N)$ 조회 — 순서 유지 필요 여부로 선택. |

### 📈 관련 키워드 및 발전 흐름도

```text
[이진 탐색 트리 BST]
    |
    v
[AVL 트리(1962) / B-Tree 대칭형(1972) / B-Tree(1972)]
    |
    v
[Red-Black 트리 정식화(1978)]
    |
    +---> [B+Tree (RDBMS 인덱스 표준)]
    +---> [LSM-Tree (쓰기 최적화 NoSQL)]
    +---> [학습 기반 인덱스 (Learned Index)]
```

### 👶 어린이를 위한 3줄 비유 설명

1. 트리는 나뭇가지처럼 갈라지는 모양이에요. 한쪽으로만 자라면(편향) 쓰러지기 쉬워서, 똑똑한 트리(AVL, Red-Black)는 새 가지를 붙일 때마다 스스로 가지치기(회전)를 해서 균형을 맞춰요.
2. B-Tree는 도서관 책장이에요. 칸 하나(노드)에 책을 여러 권 꽂아서 층수를 줄이고, 책이 너무 많아지면 칸을 둘로 나눠요(분할).
3. 균형을 맞추는 방법은 달라도(회전 vs 분할), 목표는 똑같아요 — 어떤 책이든 몇 걸음 안에 바로 찾을 수 있게 하는 것!
