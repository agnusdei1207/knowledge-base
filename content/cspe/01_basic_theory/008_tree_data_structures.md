## 미리 알고가기

- 자가 균형 트리(Self-Balancing Tree): 삽입·삭제 후 높이를 조정해 탐색 경로를 $O(\log n)$ 수준으로 유지하는 트리임
- 회전(Rotation): 부모·자식 위치를 바꿔 이진 탐색 트리 순서를 보존하면서 높이 편차를 줄이는 연산임
- 페이지(Page): 데이터베이스·파일 시스템 인덱스에서 디스크가 한 번에 읽는 블록 단위임
- 균형 인자($BF$): 왼쪽 하위 트리와 오른쪽 하위 트리 높이의 차이임
- 빈 잎 노드(NIL Leaf): 레드-블랙 트리에서 자식이 없는 위치를 나타내는 흑색 가상 노드임
- 흑색 높이(Black Height): 한 노드에서 NIL 잎까지 경로에 포함된 흑색 노드 수이며 Red-Black 트리는 모든 경로의 흑색 높이를 같게 유지함
- 편향 트리(Skewed Tree): 노드가 한쪽으로 쏠려 탐색 경로가 $O(n)$으로 퇴화한 트리임
- 95백분위 지연(p95): 측정값의 95%가 이 값 이하인 지연 시간임

## 작성 근거(검토용)

- **개요 구성**: 계층 구조와 균형 탐색 트리를 함께 잡아 일반 트리와 검색 트리의 범위를 구분함
- **Ⅱ. 특징 선정**: 키 비교, 높이 제한, 인메모리 균형 차이, 페이지 I/O는 세 트리 선택을 가름
- **Ⅲ. 비교축 선정**: 구조 원리, 성능 트레이드오프, 적합 작업은 세 트리의 설계·비용·적용 차이를 각각 드러냄
- **Ⅳ. 구조 선정**: 회전과 B-Tree 노드 구조를 함께 보여 인메모리 균형과 외부 저장소 인덱스를 구분함
- 갱신 지연과 페이지 읽기는 트리 선택 결과를 운영에서 확인하는 지표임
- **전수 검수 근거**: 제목·frontmatter·미리 알고가기·작성 근거·Ⅰ~Ⅶ 본문·표 헤더·셀·요약·결론을 5회 전수 확인했으며 금지 표현(막다), 근거 어휘(바꿈), 표 용어 불일치(메모리 색인), 불필요한 수식 감쌈($Key$)을 교정함

## Ⅰ. 개요

- **정의/개념**: 트리 구조는 부모-자식 관계로 데이터를 계층화하며, AVL·Red-Black·B-Tree는 키 탐색 경로를 균형 규칙으로 제한한 탐색 트리 계열임
- **배경/필요성**: 조회·갱신 지연을 예측 가능하게 유지하기 위해 편향을 방지하는 균형 유지 방식이 필요함

### 쉽게 이해하기 (학습용)
- 나뭇가지가 한쪽으로만 뻗으면 반대편 잎을 찾는 데 오래 걸리므로, 양쪽 가지 길이를 비슷하게 잘라주는 것과 같음

## Ⅱ. 특징

- 키 비교가 현재 노드의 왼쪽·오른쪽 또는 다분기 자식 중 이동 방향을 결정함
- 균형 조건은 트리 높이를 제한해 최악 탐색 경로를 통제함
- AVL·Red-Black은 인메모리 갱신 비용과 조회 경로 길이의 균형점이 다름
- B-Tree는 한 노드에 여러 키를 담아 디스크 페이지 읽기 횟수를 줄임

### 쉽게 이해하기 (학습용)
- 갈림길마다 크기를 비교해 왼쪽·오른쪽(또는 여러 갈래) 중 갈 길을 정함
- 나무가 너무 한쪽으로 기울지 않게 규칙으로 높이를 눌러둠
- 한 칸에 짐을 여러 개 넣을 수 있게 하면 창고를 여닫는 횟수 자체를 줄일 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree 계열 |
|:---|:---|:---|:---|
| **구조 원리** | 높이 차를 제한한 이진 탐색 트리 | 색상 규칙을 적용한 이진 탐색 트리 | 여러 키를 저장하는 다분기 탐색 트리 |
| **성능 트레이드오프** | 짧은 조회 경로·잦은 갱신 회전 | 조회 경로·갱신 조정 균형 | 페이지 I/O 감소·노드 분할 비용 |
| **적합 작업** | 조회 중심 인메모리 색인 | 갱신 중심 인메모리 색인 | 외부 저장장치 페이지 색인 |

> 요약: 조회 중심은 AVL, 갱신 중심은 Red-Black, 페이지 색인은 B-Tree가 적합함.

### 쉽게 이해하기 (학습용)
- 조회가 많으면 가지를 엄격히 맞춰두는 방법(AVL), 갱신이 많으면 색깔 표시로 느슨하게 맞추는 방법(레드-블랙), 한 번 여닫는 데 오래 걸리는 창고라면 한 칸에 여러 물건을 담는 방법(B-Tree)이 유리함

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 루트 노드 | 탐색이 시작되는 최상위 노드 |
| 분기 키 | 다음 자식 방향을 정하는 비교값 |
| 균형 메타정보 | 노드 높이·색상·키 개수 등 균형 상태를 나타내는 값 |
| 자식 포인터 | 하위 메모리 또는 페이지 위치 참조 |
| 재구성 연산 | 회전·분할·병합으로 균형 조건을 복구하는 연산 |

```text
[ 트리 재구성 - 회전 예시 ]
      (A)                         (B)
     /   \        우회전         /   \
   (B)   (C)   ----------->    (D)   (A)
   / \                               / \
 (D) (E)                           (E) (C)

[ B-Tree 노드 예시 ]
+-------------------+      +-----------------+
| K1 | K2 | K3      | ---> | P0 P1 P2 P3     |
+-------------------+      +-----------------+
```

> 요약: 탐색 트리는 분기 키로 경로를 선택하고 균형 규칙 위반 시 재구성해 높이를 제한함.

### 쉽게 이해하기 (학습용)
- 맨 위 출발점(루트), 갈림길마다 비교할 값(분기 키), 지금 얼마나 기울었는지 표시(균형 메타정보), 기울면 가지를 돌려 바로잡는 동작(재구성)이 함께 트리를 유지함

## Ⅴ. 원리 및 절차 흐름도

```text
키 비교로 위치 탐색 → 삽입·삭제 → 균형 조건 판정
                                  ├─ 충족 → 종료
                                  └─ 위반 → 회전·분할·병합 → 재검사
```

1. **탐색 및 갱신**: 키 비교로 삽입 위치나 삭제 대상을 확정함
2. **균형 확인**: 갱신 지점에서 루트 방향으로 균형 조건 위반을 점검함
3. **재구성 수행**: 회전·재색칠·분할·병합으로 조건을 회복함
4. **정합성 검증**: 탐색 순서와 높이·색상·키 개수 조건을 확인함

> 요약: 트리 갱신은 탐색 순서를 보존하면서 높이·색상·키 개수 조건을 회복해야 함.

### 쉽게 이해하기 (학습용)
- 값을 비교해 자리를 찾아 넣거나 빼고, 그 자리에서부터 위로 올라가며 기울지 않았는지 확인하고, 기울었으면 가지를 돌리거나 나눠 바로잡는 순서임

## Ⅵ. 실무 사례

1. 갱신이 잦은 인메모리 색인은 Red-Black 트리로 높이를 제한함
2. DB 인덱스는 B-Tree로 한 노드에 여러 키를 저장해 페이지 접근을 줄임

### 쉽게 이해하기 (학습용)
- 자주 바뀌는 목록은 색깔 표시로 빠르게 정리하는 방식을 쓰고, 디스크에 있는 큰 장부는 한 번 펼칠 때 여러 항목을 같이 보는 방식을 쓰는 것과 같음

## Ⅶ. 결론

- 탐색 트리는 저장 매체와 조회·갱신 비율에 맞는 균형 규칙을 선택하고 탐색 지연과 재구성 비용을 함께 확인해야 함
- 메모리 색인은 회전 비용을, 디스크 색인은 페이지 접근을 우선하므로 저장 계층과 부하 비율에 따라 트리 구조를 달리해야 함

### 쉽게 이해하기 (학습용)
- 손에 들고 다니는 수첩(메모리)과 창고 서류함(디스크)은 정리하는 방법이 다르듯, 어디에 저장하고 얼마나 자주 바꾸는지에 따라 나무를 정리하는 규칙 자체를 다르게 골라야 함
