## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 계층적 부모-자식 관계의 비선형 자료구조로, 균형 유지 방식에 따라 AVL·Red-Black·B-Tree 등으로 분류됨 |
| **배경/필요성** | 탐색·삽입·삭제를 O(log n)에 수행하려면 트리의 높이를 최소화하는 균형 유지 메커니즘이 필수임 |
| **출제 의도** | 균형 이진 탐색 트리(AVL, RB)와 다진 탐색 트리(B-Tree)의 구조·활용 차이를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|   AVL    | --> | Red-Black| --> |  B-Tree  |
| (엄격균형)|     | (완화균형)|     | (다진트리)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| AVL 트리 | 모든 노드의 좌우 서브트리 높이 차가 1 이하인 엄격 균형 이진 탐색 트리임 | 정밀 저울(항상 수평) |
| Red-Black 트리 | 노드에 색상(Red/Black)을 부여하고 5가지 규칙으로 균형을 완화 유지하는 이진 탐색 트리임 | 유연한 줄타기(약간 기울어도 OK) |
| B-Tree | 노드당 M개의 키와 M+1개의 자식을 가지며, 디스크 I/O를 최소화하는 다진 탐색 트리임 | 넓은 서랍장(한 칸에 여러 파일) |

> 요약: AVL(엄격 균형·메모리), RB(완화 균형·범용), B-Tree(다진·디스크)로 용도에 따라 선택함.

## Ⅲ. 절차
```
+------------+     +------------+
| 키삽입     | --> | 균형검사   |
| (BST규칙)  |     | (높이/색상)|
+------------+     +------------+
                        |
+------------+     +----+-------+
| 균형복원   | <-- | 회전수행   |
| 완료       |     | (LL/RR/LR)|
+------------+     +------------+
```

1. 키 삽입: BST 규칙(왼쪽 < 부모 < 오른쪽)에 따라 적절한 리프 위치에 삽입함
2. 균형 검사: AVL은 높이 차, RB는 색상 규칙, B-Tree는 노드 키 수를 검사함
3. 회전 수행: 불균형 시 LL·RR·LR·RL 회전(이진) 또는 노드 분할(B-Tree)을 수행함
4. 균형 복원: 회전·분할 후 루트까지 거슬러 올라가며 균형 조건을 재확인함

> 요약: 삽입 → 균형 검사 → 회전/분할 → 복원으로 O(log n) 높이를 유지함.

## Ⅳ. 문제점
- AVL 회전 빈발: 삽입·삭제마다 회전이 빈번하여 쓰기 성능이 RB 대비 저하됨
- RB 트리 구현 복잡성: 삽입·삭제 시 색상 변경+회전의 케이스가 다수여서 구현 난이도가 높음
- B-Tree 메모리 비효율: 인메모리 환경에서는 노드 내 빈 슬롯으로 캐시 활용률이 저하됨

## Ⅴ. 개선방안
- (단기) 라이브러리 활용: Java TreeMap(RB), C++ std::map(RB) 등 검증된 구현체를 사용함
- (중기) B+Tree 적용: 리프 노드에만 데이터를 저장하고 연결하여 범위 탐색 성능을 개선함
- (장기) LSM-Tree: 쓰기 집중 워크로드에서 B-Tree 대신 LSM(Log-Structured Merge) Tree를 적용함

## Ⅵ. 전망
- RDBMS 인덱스(B+Tree)·NoSQL(LSM-Tree)·인메모리 DB(Red-Black)에서 트리 자료구조가 핵심 역할을 하며, Learned Index(ML 기반 인덱스)가 차세대 대안으로 연구되고 있음
