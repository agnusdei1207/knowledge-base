## 미리 알고가기

- 균형 트리: 트리 높이가 한쪽으로 치우치지 않게 조정하는 트리임
- 회전: 부모와 자식의 연결을 바꿔 높이 차를 줄이는 연산임
- 차수: 한 노드가 가질 수 있는 자식 수임
- 페이지 접근: 디스크나 저장장치에서 한 번에 읽는 블록 단위 접근임

## Ⅰ. 개요

- **정의/개념**: 트리는 부모와 자식 관계로 탐색 경로를 나누는 비선형 자료구조임. AVL, Red-Black, B-Tree는 균형을 조정해 탐색 성능을 유지하는 트리임
- **배경/필요성**: 단순 이진 탐색 트리는 입력이 한쪽으로 몰리면 길이가 선형으로 늘 수 있음. 조회와 갱신 성능을 일정하게 유지하려면 균형 조정이 필요함

## Ⅱ. 특징

- AVL 트리는 높이 차를 엄격히 관리해 탐색 경로를 짧게 유지함
- Red-Black 트리는 균형 조건을 완화해 삽입과 삭제 때 조정 비용을 줄임
- B-Tree는 한 노드에 여러 키를 담아 트리 높이와 페이지 접근 수를 줄임
- 균형을 강하게 잡을수록 조회는 빨라지지만 갱신 때 재구성 비용이 늘 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree |
|:---|:---|:---|:---|
| 균형 방식 | 높이 차를 엄격히 제한 | 색상 규칙으로 완화된 균형 유지 | 노드의 키 수와 자식 수 유지 |
| 강점 | 짧은 탐색 경로 | 조회와 갱신의 균형 | 낮은 높이와 적은 페이지 접근 |
| 부담 | 갱신 때 회전이 잦을 수 있음 | AVL보다 탐색 경로가 조금 길 수 있음 | 분할과 병합 처리가 필요함 |
| 적합한 환경 | 조회 중심 메모리 구조 | 표준 라이브러리 맵 구조 | 데이터베이스와 파일 시스템 인덱스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키 | 어느 자식으로 내려갈지 정하는 비교 기준임 |
| 자식 포인터 | 다음 탐색 노드를 가리키는 연결 정보임 |
| 균형 조건 | 높이, 색상, 노드 채움률 등 트리 형태를 제한하는 규칙임 |
| 재구성 연산 | 회전, 재색칠, 분할, 병합 등 균형을 되돌리는 연산임 |

```text
+------+     +-------------+     +-----------+
| Root | --> | Internal    | --> | Leaf      |
+------+     +-------------+     +-----------+
      균형 조건으로 높이와 노드 구성을 제한함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 키 비교   | --> | 경로 이동 | --> | 삽입/삭제 | --> | 균형 복구 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 현재 노드의 키와 찾는 키를 비교함
2. 비교 결과에 따라 자식 노드로 내려감
3. 삽입이나 삭제가 끝나면 균형 조건을 확인함
4. 조건이 깨졌으면 회전, 재색칠, 분할, 병합으로 복구함

## Ⅵ. 실무 적용 및 유의점

1. 메모리 조회가 많은 구조는 AVL같이 경로를 짧게 유지하는 트리가 유리하며, 조회 지연과 회전 횟수로 확인함
2. 저장장치 기반 인덱스는 이진 트리보다 B-Tree 계열이 적합하며, 조회당 페이지 접근 수와 범위 검색 시간을 확인해야 함

## Ⅶ. 결론

- 트리 구조는 데이터 위치를 비교 경로로 좁히는 자료구조이며, 메모리 조회와 디스크 인덱스는 서로 다른 균형 기준으로 선택해야 함
