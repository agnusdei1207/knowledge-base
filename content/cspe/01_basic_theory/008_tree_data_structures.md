## 미리 알고가기

- 균형 트리: 높이 편차를 제어해 탐색 성능을 안정적으로 유지하는 트리임
- 회전: 부모와 자식 관계를 재배치해 높이 불균형을 줄이는 연산임
- 차수: 한 노드가 가질 수 있는 자식 수로, B-Tree의 높이와 I/O 횟수에 영향 줌

## Ⅰ. 개요

- **정의/개념**: AVL, Red-Black, B-Tree는 데이터 삽입 순서에 따른 편향을 제어해 탐색, 삽입, 삭제의 성능을 안정적으로 유지하도록 설계된 대표 트리 구조임
- **배경/필요성**: 단순 이진 탐색 트리는 입력 편향 시 높이가 커져 성능이 선형으로 악화되므로, 메모리 기반 조회와 디스크 기반 인덱스 모두에서 균형 유지 전략이 필요함

## Ⅱ. 특징

- AVL은 높이 균형을 엄격히 유지해 조회 경로를 짧게 만드는 데 유리함
- Red-Black은 완화된 균형 규칙으로 회전 수를 줄여 갱신 비용을 낮춤
- B-Tree는 한 노드에 여러 키를 담아 디스크 접근 횟수 자체를 줄이는 방향으로 설계됨
- 세 구조는 모두 균형을 목표로 하지만 병목 지점이 메모리 연산인지 디스크 I/O인지에 따라 선택 기준이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL | Red-Black | B-Tree |
|:---|:---|:---|:---|
| 균형 방식 | 높이 차 엄격 제어 | 색상 규칙 기반 완화 제어 | 다진 노드 채움률 관리 |
| 강점 | 조회 성능 | 갱신 균형 | 디스크 I/O 절감 |
| 대표 저장 환경 | 메모리 | 메모리 | 디스크, 페이지 캐시 |
| 대표 적용 | 조회 중심 구조 | 라이브러리, 커널 | DB 인덱스, 파일 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키와 포인터 | 탐색 기준과 하위 노드 연결 정보를 담으며 트리의 검색 경로를 결정하는 기본 구조임 |
| 균형 규칙 | 높이 차, 색상 규칙, 차수 조건 등으로 트리 높이와 성능 상한을 통제하는 기준임 |
| 재구성 연산 | 회전, 색상 변경, 분할, 병합으로 삽입과 삭제 후 깨진 균형을 복구하는 동작임 |
| 노드 크기 | 메모리 캐시 라인 또는 디스크 페이지 크기와 연관되어 특히 B-Tree 계열의 I/O 효율을 좌우하는 설계 변수임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 키비교   | --> | 위치이동 | --> | 삽입/삭제 | --> | 균형복구 |
+----------+     +----------+     +----------+     +----------+
```

1. **키비교**: 현재 노드 키와 대상 키를 비교해 다음 방향을 정함
2. **위치이동**: 리프 또는 삽입 위치까지 하위 노드로 이동함
3. **삽입/삭제**: 새 키를 넣거나 기존 키를 제거함
4. **균형복구**: 회전, 재색칠, 분할, 병합으로 성능 상한을 회복함

## Ⅵ. 문제점 및 해결 방안

1. **입력 편향으로 균형 복구 비용이 커짐**: 특정 패턴 입력은 회전이나 분할을 자주 유발함
   - **해결 방안**: 워크로드 특성에 맞는 균형 강도를 가진 트리를 선택하고 삽입당 재구성 횟수로 적합성을 검증함
2. **디스크 환경에서 메모리용 구조를 그대로 쓰면 비효율적임**: 이진 트리는 깊이가 깊어 I/O가 많아짐
   - **해결 방안**: 저장 장치 기반 인덱스는 B-Tree 계열로 설계하고 조회당 페이지 접근 수로 효과를 검증함
3. **동시성 갱신 시 상위 노드 경합이 발생함**: 재균형 과정에서 락 경합이 커질 수 있음
   - **해결 방안**: 락 범위 축소와 페이지 분리 정책을 병행하고 락 대기시간과 처리량으로 개선 여부를 검증함

## Ⅶ. 적용 사례

- 표준 라이브러리 맵 구조: Red-Black으로 조회와 갱신의 균형을 맞춤, 확인 지표는 탐색 시간과 삽입 비용임
- 메모리 조회 집중 시스템: AVL로 경로 길이를 짧게 유지함, 확인 지표는 조회 지연시간과 회전 횟수임
- 관계형 데이터베이스: B-Tree로 페이지 수를 줄여 범위 검색을 처리함, 확인 지표는 페이지 접근 수와 인덱스 탐색 시간임

## Ⅷ. 결론

트리 구조 선택의 핵심은 균형 유지 방식 자체보다 어떤 병목을 줄일 것인지에 있으므로, 메모리 조회 중심인지 디스크 인덱스 중심인지에 따라 AVL, Red-Black, B-Tree를 구분해 써야 함.
