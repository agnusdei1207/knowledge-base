## Ⅰ. 개요
- **정의**: 노드와 간선으로 구성된 비순환 계층 자료구조로, 탐색·삽입·삭제를 로그 시간에 수행함
- **배경/필요성**: 선형 구조(007 참조)에서는 탐색에 O(n)이 소요되므로, 데이터 규모 증가 시 로그 시간 접근을 보장하는 계층 구조가 필요함
- **비유**: 조직도 — 최상위 대표(루트)에서 부서(서브트리)로 분기하며, 특정 직원을 찾을 때 전체를 순회하지 않고 소속 부서를 따라 내려감

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 균형 트리의 존재 이유와 종류별 차이 | BST 편향 문제, AVL·Red-Black 회전 연산, B-Tree의 디스크 I/O 최적화 원리 | BST만 설명하고 균형 유지 메커니즘을 빠뜨리면 감점, B-Tree의 다진 분기 이유 언급 필요 |

> 요약: 계층 구조를 통해 로그 시간 연산을 보장하며, 균형 유지 방식에 따라 AVL·Red-Black·B-Tree로 분화함

## Ⅱ. 구성요소
```text
            [BST]
           /     \
      [AVL]       [Red-Black]
     균형 엄격      균형 완화
     |h| <= 1      흑색 높이 균일
                        |
                    [B-Tree]
                  다진 분기(M-way)
                  디스크 블록 정렬
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| BST (이진 탐색 트리) | 왼쪽 자식 < 부모 < 오른쪽 자식 규칙으로 탐색 O(log n), 편향 시 O(n) | 사전: 중간 페이지를 펴서 앞/뒤를 결정 |
| AVL 트리 | 모든 노드의 좌우 서브트리 높이 차이를 1 이하로 유지, 삽입·삭제 시 회전 수행 | 정밀 저울: 한쪽이 기울면 즉시 균형 추를 옮김 |
| Red-Black 트리 | 노드에 색상(Red/Black)을 부여하고 5가지 속성으로 흑색 높이 균일성을 유지 | 신호등 규칙: 빨간 불 연속 금지 등 규칙으로 전체 흐름 균형 유지 |
| B-Tree | 하나의 노드에 M-1개 키를 저장하여 트리 높이를 낮추고 디스크 블록 단위 접근에 최적화 | 서류 캐비닛: 서랍 하나에 여러 폴더를 넣어 캐비닛 열림 횟수를 줄임 |

> 요약: BST를 기반으로 메모리 환경에는 AVL·Red-Black, 디스크 환경에는 B-Tree가 균형을 유지함

## Ⅲ. 절차
```text
[키 입력] --> [탐색 위치 결정] --> [삽입/삭제 수행] --> [균형 복원]
```
- 1단계: 삽입·삭제·탐색할 키 값을 입력받음
- 2단계: BST 속성(왼쪽 < 부모 < 오른쪽)에 따라 루트에서 리프 방향으로 탐색하여 대상 위치를 결정함
- 3단계: 해당 위치에서 삽입 또는 삭제를 수행함
  - 삭제 시 자식이 2개인 노드는 중위 후속자(in-order successor)로 대체
- 4단계: 균형 조건 위반 여부를 검사하고 복원함
  - AVL: 높이 차이 > 1이면 LL/RR/LR/RL 회전 수행
  - Red-Black: 색상 속성 위반 시 재색칠 또는 회전 수행
  - B-Tree: 노드 오버플로 시 분할(split), 언더플로 시 병합(merge) 수행

> 요약: BST 규칙으로 위치를 결정한 뒤 삽입·삭제를 수행하고, 트리 유형별 균형 복원 연산을 적용함

## Ⅳ. 문제점
- BST 편향: 정렬된 데이터 삽입 시 한쪽으로 치우쳐 높이가 n이 되어 탐색 O(n)으로 퇴화함 — 로그 시간 보장이 깨짐
- AVL 회전 빈도: 삽입·삭제마다 높이 차이를 1 이하로 유지하므로 회전 연산이 빈번함 — 삭제가 잦은 워크로드에서 오버헤드 증가
- B-Tree 메모리 비효율: 노드 내 키 배열과 자식 포인터 배열을 유지해야 하므로 메모리 상주 시 공간 오버헤드가 큼 — 메모리 기반 인덱스에는 부적합

> 요약: BST는 편향, AVL은 회전 빈도, B-Tree는 메모리 오버헤드에서 각각 한계를 가짐

## Ⅴ. 개선방안
1. 단기: Red-Black 트리 적용으로 BST 편향 방지 — AVL 대비 회전 횟수가 적어 범용 균형 트리로 활용 가능(삽입 시 최대 2회, 삭제 시 최대 3회 회전)
2. 중기: AVL 트리를 읽기 집중 워크로드에 한정 적용하고, 삭제 빈번 환경에서는 Red-Black으로 대체하여 회전 오버헤드를 절감
3. 장기: B+ Tree 도입으로 리프 노드에만 데이터를 저장하고 리프 간 연결 리스트를 구성하여 범위 질의 성능을 확보하고 내부 노드의 메모리 사용을 절감

> 요약: Red-Black으로 편향을 방지하고, 워크로드별 트리를 분리하며, B+ Tree로 범위 질의까지 최적화함

## Ⅵ. 전망
- 발전 방향: LSM-Tree 등 쓰기 최적화 구조와 B-Tree 계열의 하이브리드 인덱스 연구가 확대되고 있음
- 기술사적 판단: 트리 구조는 DBMS 인덱스, 파일 시스템, 메모리 할당기 등 시스템 소프트웨어의 핵심 기반이므로 균형 유지 원리의 이해가 필수임
- 기술사 제언: 트리 선택 시 읽기/쓰기 비율, 저장 매체(메모리/디스크), 범위 질의 필요 여부를 기준으로 판단해야 하며, 순회 방식은 이진트리 순회(009 참조)를 함께 학습할 것을 권장함
