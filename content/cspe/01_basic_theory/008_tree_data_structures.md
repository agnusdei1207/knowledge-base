## 미리 알고가기

- 자가 균형 트리(Self-Balancing Tree): 삽입·삭제 후 높이를 조정해 탐색 성능($O(\log n)$)을 유지하는 트리임
- 회전(Rotation): 부모·자식 위치를 바꿔 한쪽 쏠림을 줄이는 연산임
- 페이지(Page): 디스크 인덱스의 최소 입출력 단위임
- 균형 인자($BF$): 왼쪽 서브트리 높이와 오른쪽 서브트리 높이의 차이임
- 편향 트리(Skewed Tree): 노드가 한쪽으로만 쏠려 탐색 성능이 $O(n)$으로 퇴화한 이진 탐색 트리임

## Ⅰ. 개요

- **정의/개념**: 트리 자료구조는 부모-자식 관계로 데이터를 계층화하는 비선형 구조임. AVL·Red-Black·B-Tree는 높이 또는 노드 채움률을 통제하는 균형 탐색 트리임
- **배경/필요성**: 단순 이진 탐색 트리는 정렬 입력에서 편향 트리로 퇴화함. 입력 순서와 무관하게 탐색 지연을 $O(\log n)$으로 통제할 기법이 필요함

## Ⅱ. 특징

- 키 비교로 탐색 범위를 단계별로 줄임
- 균형 조건으로 최악 높이를 제한함
- AVL은 탐색 경로를 짧게 유지함
- Red-Black은 재색칠 중심으로 갱신 부담을 낮춤
- B-Tree는 다분기 노드로 페이지 I/O를 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree (B+/B*) |
|:---|:---|:---|:---|
| **균형 원리** | 균형 인자 절댓값 1 이하 | 색상(R/B) 규칙 기반 완화 균형 | 노드 내 키/자식 개수 범위 유지 |
| **탐색 성능** | 경로 가장 짧음 | AVL보다 길 수 있음 | 디스크 I/O에 유리함 |
| **갱신 비용** | 회전 빈도 높음 | 재색칠 중심 조정 | 분할·병합 비용 발생 |
| **주요 활용** | 조회 중심 인메모리 검색 | Java TreeMap, 리눅스 커널 | DB 인덱스, 파일 시스템 |

> 요약: 조회 중심은 AVL, 갱신 중심은 Red-Black, 외부 저장소 인덱스는 B-Tree가 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 루트 노드 | 모든 탐색이 시작되는 최상단 노드임 |
| 분기 키($Key$) | 값의 대소를 비교해 이동 방향을 정하는 기준값임 |
| 균형 메타정보 | 균형 인자, 색상, 키 개수처럼 재구성 여부를 판단하는 상태값임 |
| 자식 포인터 | 하위 노드의 메모리 주소 또는 디스크 블록 주소임 |

```text
[ 트리 재구성 - 회전 예시 ]
      (A)                         (B)
     /   \       Right Rot       /   \
   (B)   (C)   ----------->    (D)   (A)
   / \                               / \
 (D) (E)                           (E) (C)

[ B-Tree 노드 예시 ]
+-------------------+      +-----------------+
| K1 | K2 | K3      | ---> | P0 P1 P2 P3     |
+-------------------+      +-----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 탐색 및 갱신 | --> | 균형 상태 확인 | --> | 재구성 연산  | --> | 정합성 검증  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **탐색 및 갱신** — 키를 비교하며 삽입 위치나 삭제 대상을 확정함
2. **균형 확인** — 부모 방향으로 올라가며 균형 조건 위반을 점검함
3. **재구성 수행** — 회전, 재색칠, 분할·병합으로 조건을 회복함
4. **정합성 검증** — 모든 경로가 균형 조건을 만족하는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 갱신 많은 인메모리 색인은 Red-Black이 적합하며, p95 갱신 지연과 회전 횟수로 확인함
2. DB 인덱스는 B-Tree 계열이 적합하며, 트리 높이·페이지 읽기·노드 분할 빈도로 확인함

## Ⅶ. 결론

- 트리 구조는 저장 위치와 조회·갱신 비율에 맞는 균형 기준을 선택해 탐색 지연과 재구성 비용을 통제함
