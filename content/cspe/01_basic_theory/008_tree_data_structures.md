# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 노드들이 부모-자식 관계의 계층적 구조로 연결된 **비선형 자료구조**. (Cycle이 없는 연결 그래프)
- **핵심 목표**: 데이터의 계층적 표현뿐만 아니라, **$O(\log N)$**의 고속 탐색/삽입/삭제 성능을 확보하는 것.
- **핵심 직관**: "데이터를 피라미드 형태로 쌓아, 매 결정마다 후보군을 획기적으로 줄인다."

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **루트 (Root)** | 트리의 최상위 노드 | 가계도의 시조, 조직도의 회장님 |
| **차수 (Degree)** | 노드가 가진 자식 노드의 수 | "내 밑으로 몇 명인가?" |
| **높이 (Height)** | 루트에서 리프까지 가장 긴 경로의 길이 | "몇 층짜리 건물인가?" |
| **균형 (Balance)** | 좌우 서브트리의 높이가 비슷하게 유지됨 | 치우치지 않은 저울 |
| **편향 (Skew)** | 한쪽으로만 자라 리스트처럼 된 트리 | 사실상 연결 리스트 ($O(N)$ 퇴화) |

## 깊이 이해

- **이진 탐색 트리(BST)의 숙명**: 
  BST는 "왼쪽 자식 < 부모 < 오른쪽 자식"의 규칙을 가집니다. 평균적으로 $O(\log N)$이나, 정렬된 데이터를 순서대로 넣으면 한 줄로 길게 자라 $O(N)$으로 변질됩니다. 이를 막기 위해 스스로 균형을 잡는 **자가 균형 트리(Self-Balancing Tree)**가 등장했습니다.

- **자가 균형 트리의 3대 천왕**:
  1. **AVL Tree**: 가장 엄격한 균형. 높이 차가 1 이하로 유지. 탐색 성능이 최강이나 삽입/삭제 시 회전(Rotation)이 잦음.
  2. **Red-Black Tree**: 약간 느슨한 균형. 규칙이 복잡하지만 회전 횟수가 적어 삽입/삭제 성능이 우수. (Java `TreeMap`, C++ `map`의 근간)
  3. **B-Tree**: 이진이 아닌 다진(m-way) 트리. 한 노드에 여러 키를 담아 높이를 획기적으로 낮춤. (DB 인덱스의 표준)

- **디스크와 B-Tree**: 
  메모리는 한 바이트씩 읽어도 빠르지만, 디스크(SSD/HDD)는 페이지(Page) 단위로 크게 읽어야 효율적입니다. B-Tree는 노드 하나를 디스크 페이지 크기에 맞춰, 단 몇 번의 이동($O(\log_m N)$)만으로 수십억 건의 데이터를 찾아냅니다.

- **일상 비유 (도서 분류)**: 
  - **BST**: 사서가 책을 꽂을 때, 제목 순서대로 꽂음. (가나다 순)
  - **B-Tree**: 서점 섹션 분류. (인문 -> 철학 -> 니체) 한 번 섹션 문을 열면 그 안에 수많은 책이 모여 있음.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 계층적 관계를 통해 탐색 범위를 로그 스케일($O(\log N)$)로 압축하는 **비선형 계층 자료구조**임.
> 2. **가치**: 데이터의 동적 삽입/삭제 시에도 **자가 균형 메커니즘**을 통해 시스템 성능의 하한선(Worst-case)을 보장함.
> 3. **선택 포인트**: 인메모리 대량 연산은 **Red-Black**, 디스크 기반 대규모 저장소는 **B+Tree**를 선정하는 것이 아키텍처의 정석임.

## Ⅰ. 효율적 탐색의 아키텍처, 트리 자료구조의 개요
### 1. 정의
- 노드와 간선으로 이루어져 있으며, 임의의 두 노드 사이에 유일한 경로가 존재하고 사이클이 없는 계층적 구조.
### 2. 주요 분류
- **이진 트리 (Binary Tree)**: 모든 노드의 차수가 2 이하인 트리.
- **균형 트리 (Balanced Tree)**: 높이 편차를 최소화하여 탐색 성능을 최적화한 트리.
- **다진 트리 (Multi-way Tree)**: 노드당 2개 이상의 자식을 가져 높이를 극단적으로 낮춘 트리.

## Ⅱ. 자가 균형 탐색 트리(Balanced BST) 비교 분석
| 구분 | AVL 트리 | Red-Black 트리 | B-트리 계열 (B-Tree/B+Tree) |
|:---:|:---|:---|:---|
| **균형 조건** | 높이 차(BF) $\le 1$ | 5가지 색상 규칙 준수 | 노드 내 키 개수 ($M/2 \sim M$) |
| **균형 강도** | **엄격 (Strict)** | 느슨 (Relaxed) | 다진 분할을 통한 높이 최소화 |
| **연산 성능** | 탐색 성능 극대화 | 삽입/삭제 성능 우수 | 디스크 I/O 최적화 |
| **적용 사례** | 사전(Dictionary) 검색 | **OS 스케줄러, 실시간 맵** | **RDBMS 인덱스, 파일 시스템** |

## Ⅲ. B-Tree 및 B+Tree의 매커니즘 (DB 핵심)
### 1. B-Tree: 모든 노드에 데이터 저장
- 루트부터 리프까지 모든 노드가 키와 데이터를 가짐.
- 특정 키 발견 시 탐색 조기 종료 가능.
### 2. B+Tree: 리프 노드에만 데이터 저장
- 내부 노드는 가이드(Index) 역할만 수행.
- 리프 노드들이 **연결 리스트(Linked List)**로 이어져 있어 **Full Scan(범위 검색)**에 압도적 효율.
- 현대 관계형 데이터베이스(MySQL, Oracle 등)의 표준 인덱스 구조.

## Ⅳ. 특수 목적 트리 자료구조
### 1. T-Tree
- AVL 트리와 B-Tree의 장점을 결합. 인메모리 데이터베이스(ALTIBASE 등)에 최적화.
### 2. Splay Tree
- 최근에 접근한 노드를 루트로 옮김. 자주 찾는 데이터에 대해 $O(1)$에 가까운 속도 보장 (Locality 활용).
### 3. Trie (접두사 트리)
- 문자열 탐색에 최적화. 자동 완성, IP 라우팅 테이블 조회 등에 활용.

## Ⅴ. 기술사 관점의 성능 튜닝 및 고려사항
### 1. 트리 높이 제어 (Height Management)
- 트리 높이가 $H$일 때 탐색 비용은 $O(H)$. B-Tree의 경우 차수(Order)를 크게 하여 $H$를 3~4 이내로 관리하는 것이 관건.
### 2. 동시성 제어 (Concurrency Control)
- 다중 사용자가 트리를 갱신할 때 발생하는 Lock 경합 문제.
- **대응**: 래치 프리(Latch-free) 트리 또는 **B-link Tree** 기법을 통한 처리량(Throughput) 개선.

## Ⅵ. 기술사 관점의 결론: "데이터 규모와 매체에 따른 전략적 선택"
- 트리는 단순히 '빠른 탐색'을 넘어, 데이터가 저장되는 **물리적 매체(Memory vs Disk)**와 **접근 패턴(Point vs Range)**에 따라 그 형태가 진화해 왔음.
- 미래의 아키텍트는 비정형 빅데이터와 실시간 처리를 위해 **LSM-Tree(쓰기 최적화)**나 **분산 트리(Distributed Tree)** 구조를 적극 도입하여 데이터 폭증 시대의 병목을 해결해야 함.
