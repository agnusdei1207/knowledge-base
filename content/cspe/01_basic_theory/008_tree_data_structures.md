# 트리 구조 - B-Tree·AVL·Red-Black (Tree Data Structures)

## 1. 정의 및 개념

트리는 노드(Node)와 간선(Edge)의 부모-자식 관계로 계층 구조를 표현하는 비선형 자료구조이다. 검색 트리는 키의 순서 관계를 이용하여 탐색·삽입·삭제를 효율화한다.

| 구분 | 정의 | 핵심 특징 |
|---|---|---|
| **Binary Search Tree(BST)** | 왼쪽 < 루트 < 오른쪽 순서를 만족하는 이진 검색 트리 | 편향 시 `O(n)` |
| **AVL Tree** | 좌우 서브트리 높이 차를 엄격히 제한하는 균형 BST | 탐색 빠름, 회전 많음 |
| **Red-Black Tree** | 색상 규칙으로 완화된 균형을 유지하는 BST | 갱신 성능 균형 |
| **B-Tree** | 하나의 노드가 여러 키와 자식을 갖는 다진 균형 검색 트리 | 디스크·DB 인덱스에 적합 |

## 2. 구조 및 주요 연산

**공통 연산**
- search: 키 비교를 통해 하위 노드로 이동
- insert: 키 위치를 찾아 삽입 후 균형 조건 복구
- delete: 대상 키 삭제 후 회전·병합 등으로 불변식 유지
- traversal: 중위 순회 등으로 정렬된 키 순회
- range query: 특정 키 범위의 데이터 탐색

```text
        Root
       /    \
  Left Sub   Right Sub
```

트리 성능은 루트에서 리프까지의 높이에 좌우되며, 균형이 깨지면 탐색 비용이 급격히 증가한다.

## 3. B-Tree·AVL·Red-Black 비교

| 구분 | B-Tree | AVL Tree | Red-Black Tree |
|---|---|---|---|
| 구조 | 다진 검색 트리 | 엄격한 균형 이진 트리 | 완화된 균형 이진 트리 |
| 균형 기준 | 노드 키 개수와 자식 수 | 좌우 높이 차 | 색상 규칙 |
| 탐색 비용 | `O(log_m n)` | `O(log n)` | `O(log n)` |
| 갱신 비용 | 분할·병합 | 회전 빈번 | 회전 상대적으로 적음 |
| 주요 적용 | DB, 파일시스템, 디스크 인덱스 | 조회 중심 메모리 구조 | 범용 map/set |

B-Tree는 Binary Tree가 아니라 다진 트리이며, 페이지 단위 I/O를 줄이기 위해 한 노드에 여러 키를 저장한다.

## 4. 응용 분야

- 데이터베이스 인덱스(B-Tree, B+Tree)
- 파일시스템 디렉터리·블록 인덱스
- 운영체제 메모리 영역 관리
- 언어 런타임의 map/set 구현
- 라우팅 테이블, 범위 검색
- 컴파일러의 구문 트리(Abstract Syntax Tree, AST)
- 계층형 조직도·분류 체계 표현

## 5. 심화 이슈 (기술사 포인트)

1. **편향 트리 문제**
   - 일반 BST는 정렬된 데이터가 순서대로 삽입되면 높이가 `n`이 되어 탐색이 `O(n)`으로 악화된다.

2. **균형 유지 비용**
   - AVL은 탐색 성능이 좋지만 회전이 잦고, Red-Black은 갱신과 탐색 사이의 절충을 제공한다.

3. **저장 매체 고려**
   - 메모리 내부 구조에는 AVL/RB가 적합하고, 디스크 기반 인덱스에는 B-Tree/B+Tree가 적합하다.

4. **동시성 제어**
   - DB 인덱스에서는 노드 단위 latch, latch coupling, MVCC 등이 필요하다.

5. **LSM Tree와 비교**
   - 쓰기 집약 워크로드에서는 B-Tree보다 LSM Tree가 유리할 수 있으나 읽기 증폭·compaction 비용을 고려해야 한다.

## 6. 결론

트리 구조는 계층 표현과 정렬 기반 탐색을 동시에 제공하는 핵심 자료구조이다. 기술사 답안에서는 트리의 높이와 균형 유지가 성능을 좌우한다는 점을 중심으로, B-Tree·AVL·Red-Black Tree를 저장 매체, 조회/갱신 비율, 범위 질의 요구에 따라 비교해야 한다.
