## 미리 알고가기

- 균형 트리: 높이 편차를 제어해 탐색 성능을 안정적으로 유지하는 트리임
- 회전: 부모와 자식 관계를 재배치해 높이 불균형을 줄이는 연산임
- 차수: 한 노드가 가질 수 있는 자식 수로, B-Tree의 높이와 I/O 횟수에 영향 줌

## Ⅰ. 개요

- **정의/개념**: 트리 구조는 부모-자식 계층 관계로 데이터를 조직해 탐색 경로를 분기하는 비선형 자료구조이며, AVL, Red-Black, B-Tree는 그중 높이와 노드 구조를 제어해 탐색, 삽입, 삭제 성능을 안정적으로 유지하는 대표 균형 트리 계열임
- **배경/필요성**: 단순 이진 탐색 트리는 입력 편향 시 높이가 커져 성능이 선형으로 악화되므로, 메모리 기반 조회와 디스크 기반 인덱스 모두에서 균형 유지 전략이 필요함

## Ⅱ. 특징

- AVL은 높이 균형을 엄격히 유지해 조회 경로를 짧게 만드는 데 유리함
- Red-Black은 완화된 균형 규칙으로 회전 수를 줄여 갱신 비용을 낮춤
- B-Tree는 한 노드에 여러 키를 담아 디스크 접근 횟수 자체를 줄이는 방향으로 설계됨
- 세 구조는 모두 균형을 유지하지만, 줄여야 할 병목이 메모리 연산인지 디스크 I/O인지에 따라 쓰임이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL | Red-Black | B-Tree |
|:---|:---|:---|:---|
| 균형 방식 | 높이 차 엄격 제어 | 색상 규칙 기반 완화 제어 | 다진 노드 채움률 관리 |
| 강점 | 조회 성능 | 갱신 균형 | 디스크 I/O 절감 |
| 대표 저장 환경 | 메모리 | 메모리 | 디스크, 페이지 캐시 |
| 대표 적용 | 조회 중심 구조 | 라이브러리, 커널 | DB 인덱스, 파일 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키와 포인터 | 탐색 기준과 하위 노드 연결 정보를 담으며 트리의 검색 경로를 결정하는 기본 구조임 |
| 균형 규칙 | 높이 차, 색상 규칙, 차수 조건 등으로 트리 높이와 성능 상한을 통제하는 기준임 |
| 재구성 연산 | 회전, 색상 변경, 분할, 병합으로 삽입과 삭제 후 깨진 균형을 복구하는 동작임 |
| 노드 크기 | 메모리 캐시 라인 또는 디스크 페이지 크기와 연관되어 특히 B-Tree 계열의 I/O 효율을 좌우하는 설계 변수임 |

```text
+---------+     +-------------+     +-------------+
| 루트 노드  | --> | 자식 포인터들   | --> | 리프/데이터 경로 |
+---------+     +-------------+     +-------------+
      |
      v
+-------------+     +-------------+
| 균형 규칙    | --> | 회전/분할 복구  |
+-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 키비교   | --> | 위치이동 | --> | 삽입/삭제 | --> | 균형복구 |
+----------+     +----------+     +----------+     +----------+
```

1. **키비교**: 현재 노드 키와 대상 키를 비교해 다음 방향을 정함
2. **위치이동**: 리프 또는 삽입 위치까지 하위 노드로 이동함
3. **삽입/삭제**: 새 키를 넣거나 기존 키를 제거함
4. **균형복구**: 회전, 재색칠, 분할, 병합으로 성능 상한을 회복함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 정렬된 키가 계속 들어오면 단순 이진 탐색 트리는 한쪽으로 치우쳐 탐색 시간이 $O(n)$까지 늘어날 수 있음
   - 해결방안: AVL이나 Red-Black처럼 높이를 자동 보정하는 균형 트리를 적용하고, 트리 높이와 탐색 비교 횟수가 $O(\log n)$ 범위에 머무는지 확인함
2. 문제: 조회 성능만 보고 AVL을 선택하면 삽입·삭제가 많은 환경에서 회전 비용이 누적되어 갱신 처리량이 떨어질 수 있음
   - 해결방안: 조회가 많을 때는 AVL, 갱신이 많을 때는 Red-Black처럼 균형 강도를 다르게 적용하고, 같은 입력에서 조회 시간과 삽입·삭제 시간을 비교함
3. 문제: 디스크 인덱스를 이진 트리로 구성하면 트리 높이만큼 페이지 I/O가 누적되어 범위 검색이 느려짐
   - 해결방안: 디스크 기반 인덱스는 한 페이지에 여러 키를 담는 B-Tree 계열로 설계하고, 조회당 페이지 읽기 수와 범위 스캔 시간이 줄었는지 확인함

## Ⅶ. 적용 사례

- 정렬 순회가 필요한 표준 라이브러리 맵은 Red-Black Tree로 탐색과 삽입·삭제를 모두 $O(\log n)$로 유지하며, 실제 구현에서는 연산 시간과 회전 부담을 함께 확인함
- 메모리에서 조회가 갱신보다 많은 색인 구조는 AVL로 최대 탐색 경로를 짧게 유지하고, 조회 지연시간이 줄어드는지와 삽입·삭제 회전 부담이 허용되는지 비교함
- 관계형 데이터베이스 인덱스는 B-Tree 계열로 한 페이지에 여러 키를 저장해 범위 검색 시 읽는 페이지 수를 줄이며, 페이지 읽기 수와 인덱스 스캔 시간으로 효과를 판단함

## Ⅷ. 결론

트리 구조를 고를 때는 균형 규칙 이름보다 줄여야 할 병목을 먼저 봐야 하며, 메모리 조회에는 AVL과 Red-Black을, 디스크 인덱스에는 B-Tree 계열을 구분해 써야 함.
