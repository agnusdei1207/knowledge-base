## 미리 알고가기

- 자가 균형 트리(Self-Balancing Tree): 삽입·삭제 시 스스로 높이를 조절하여 탐색 성능($O(\log n)$)을 유지하는 트리임
- 회전(Rotation): 부모와 자식 노드의 위치를 바꾸어 특정 방향으로 쏠린 트리의 높이 차를 줄이는 연산임
- 페이지(Page): 디스크 인덱스 관리의 최소 단위이며, B-Tree는 한 노드를 페이지 크기에 맞춰 I/O 횟수를 최소화함
- 편향 트리(Skewed Tree): 노드가 한쪽으로만 쏠려 탐색 성능이 $O(n)$으로 퇴화한 이진 탐색 트리임

## Ⅰ. 개요

- **정의/개념**: 트리는 노드 간 부모-자식 관계를 형성하여 데이터를 계층적으로 구조화하고 탐색 경로를 분기하는 비선형 자료구조이며, 자가 균형 트리는 높이 불균형을 자동으로 교정하는 변형 구조임
- **배경/필요성**: 단순 이진 탐색 트리는 정렬된 데이터가 입력될 경우 편향 트리로 변질되어 성능이 급격히 저하되므로, 어떠한 입력 패턴에서도 최악의 탐색 지연을 $O(\log n)$으로 통제할 기법이 필요함

## Ⅱ. 특징

- AVL 트리는 왼쪽과 오른쪽 서브트리의 높이 차를 1 이하로 엄격히 관리하여, 모든 자가 균형 트리 중 가장 짧은 탐색 경로를 보장함
- Red-Black 트리는 노드 색상과 느슨한 균형 규칙을 적용하여 삽입·삭제 시 발생하는 재구성(회전) 횟수를 줄임으로써 갱신 빈도가 높은 환경에 최적화됨
- B-Tree는 하나의 노드에 다량의 키를 담는 다차원 구조를 가져, 트리 전체의 높이를 획기적으로 낮춤으로써 디스크 I/O 발생 빈도를 최소화함

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree (B+/B*) |
|:---|:---|:---|:---|
| **균형 원리** | $BF \le 1$ 높이 차 엄격 제한 | 색상(R/B) 규칙 기반 완화 균형 | 노드 내 키/자식 개수 범위 유지 |
| **탐색 성능** | 매우 우수 (최단 경로) | 우수 (AVL보다 조금 길 수 있음) | 우수 (I/O 횟수에 최적화) |
| **갱신 오버헤드** | 높음 (빈번한 회전 발생) | 낮음 (재색칠 위주 조정) | 중간 (분할/병합 시 지연) |
| **주요 활용** | 조회 중심 인메모리 검색 | $Java$ $TreeMap$, 리눅스 커널 | $DB$ 인덱스, 파일 시스템 |

> 요약: 조회 성능이 최우선이면 AVL을, 삽입·삭제가 빈번하면 Red-Black을, 대규모 데이터의 외부 저장소 인덱스에는 B-Tree를 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 루트 노드 | 트리의 최상단 진입점이며, 모든 탐색 연산이 시작되는 고유 노드임 |
| 분기 키 ($Key$) | 데이터 값의 대소를 비교하여 탐색할 서브트리 방향을 결정하는 기준값임 |
| 균형 인자 ($BF$) | AVL 등에서 좌우 서브트리의 높이 차이를 나타내며 재구성 연산의 트리거가 됨 |
| 자식 포인터 | 하위 계층 노드의 메모리 주소나 디스크 블록 주소를 저장하는 연결 정보임 |

```text
[ 트리 재구성 - 회전 예시 ]
      (A)                         (B)
     /   \       Right Rot       /   \
   (B)   (C)   ----------->    (D)   (A)
   / \                               / \
 (D) (E)                           (E) (C)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 탐색 및 삽입 | --> | 균형 상태 확인 | --> | 재구성 연산  | --> | 정합성 검증  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **탐색 및 삽입** — 루트부터 키를 비교하며 내려가 리프 노드에 데이터를 추가하거나 삭제를 수행함
2. **균형 확인** — 연산 후 부모 노드로 거슬러 올라가며 높이 차($BF$)나 색상 규칙, 노드 채움률 위반 여부를 점검함
3. **재구성 수행** — 규칙 위반 시 단일/이중 회전(AVL, RB), 재색칠(RB), 또는 노드 분할/병합(B-Tree)을 실행함
4. **정합성 검증** — 재구성이 완료된 후 트리의 모든 경로가 정의된 균형 조건을 만족하는지 최종적으로 확인함

## Ⅵ. 실무 적용 및 유의점

1. 메모리상에서 빈번한 검색이 발생하는 라이브러리 설계 시에는 AVL 트리의 짧은 탐색 경로가 유리하지만, 실시간 주식 호가 데이터처럼 갱신이 쏟아지는 환경에서는 회전 비용이 적은 Red-Black 트리를 채택하여 CPU 부하를 분산해야 함
2. 데이터베이스 인덱스 설계 시 이진 트리를 사용하면 트리가 깊어져 디스크 탐색($Seek$) 횟수가 폭증하므로, 노드 크기를 디스크 블록($Page$)에 맞춰 높이를 최소화한 B-Tree 계열을 적용하고 노드 분할 시 발생하는 일시적 지연을 통제해야 함

## Ⅶ. 결론

- 트리 구조는 데이터의 정렬 상태와 계층성을 동시에 확보하는 핵심 메커니즘이며, 실무자는 가용 자원($RAM$ vs $Disk$)과 질의 패턴(조회 vs 갱신)에 따라 최적의 자가 균형 알고리즘을 선별하여 시스템의 확장성을 확보해야 함
