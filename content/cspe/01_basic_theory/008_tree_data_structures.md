## 미리 알고가기

- 자가 균형 트리(Self-Balancing Tree): 삽입·삭제 시 스스로 높이를 조절하여 탐색 성능($O(\log n)$)을 유지하는 트리임
- 회전(Rotation): 부모와 자식 노드의 위치를 바꾸어 특정 방향으로 쏠린 트리의 높이 차를 줄이는 연산임
- 페이지(Page): 디스크 인덱스 관리의 최소 단위이며, B-Tree는 한 노드를 페이지 크기에 맞춰 I/O 횟수를 최소화함
- 편향 트리(Skewed Tree): 노드가 한쪽으로만 쏠려 탐색 성능이 $O(n)$으로 퇴화한 이진 탐색 트리임

## Ⅰ. 개요

- **정의/개념**: 트리 자료구조는 부모-자식 관계로 데이터를 계층화하고 키 비교로 탐색 범위를 줄이는 비선형 구조이며, AVL·Red-Black·B-Tree는 높이 또는 노드 채움률을 통제해 탐색 비용을 일정 수준으로 유지하는 균형 탐색 트리임
- **배경/필요성**: 단순 이진 탐색 트리는 정렬된 데이터가 입력될 경우 편향 트리로 변질되어 성능이 급격히 저하되므로, 어떠한 입력 패턴에서도 최악의 탐색 지연을 $O(\log n)$으로 통제할 기법이 필요함

## Ⅱ. 특징

- AVL 트리는 좌우 서브트리 높이 차를 1 이하로 엄격히 제한하여 대표 균형 이진 탐색 트리 중 탐색 경로를 짧게 유지함
- Red-Black 트리는 색상 규칙과 재색칠을 활용해 균형 조건을 완화하므로 삽입·삭제가 많은 환경에서 재구성 비용을 상대적으로 줄일 수 있음
- B-Tree는 한 노드에 여러 키와 자식 포인터를 저장하는 다분기 구조로 트리 높이를 낮춰 페이지 I/O 횟수를 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | AVL 트리 | Red-Black 트리 | B-Tree (B+/B*) |
|:---|:---|:---|:---|
| **균형 원리** | 균형 인자 절댓값 1 이하 | 색상(R/B) 규칙 기반 완화 균형 | 노드 내 키/자식 개수 범위 유지 |
| **탐색 성능** | 높이 엄격 제한으로 탐색 경로가 짧음 | AVL보다 조금 길 수 있음 | 페이지 I/O 횟수에 최적화 |
| **갱신 오버헤드** | 높음 (빈번한 회전 발생) | 낮음 (재색칠 위주 조정) | 중간 (분할/병합 시 지연) |
| **주요 활용** | 조회 중심 인메모리 검색 | Java TreeMap, 리눅스 커널 | DB 인덱스, 파일 시스템 |

> 요약: 조회 성능이 최우선이면 AVL을, 삽입·삭제가 빈번하면 Red-Black을, 대규모 데이터의 외부 저장소 인덱스에는 B-Tree를 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 루트 노드 | 트리의 최상단 진입점이며, 모든 탐색 연산이 시작되는 고유 노드임 |
| 분기 키 ($Key$) | 데이터 값의 대소를 비교하여 탐색할 서브트리 방향을 결정하는 기준값임 |
| 균형 메타정보 | AVL의 균형 인자, Red-Black의 색상, B-Tree의 키 개수·채움률처럼 재구성 여부를 판단하는 상태값임 |
| 자식 포인터 | 하위 계층 노드의 메모리 주소나 디스크 블록 주소를 저장하는 연결 정보임 |

```text
[ 트리 재구성 - 회전 예시 ]
      (A)                         (B)
     /   \       Right Rot       /   \
   (B)   (C)   ----------->    (D)   (A)
   / \                               / \
 (D) (E)                           (E) (C)

[ B-Tree 노드 예시 ]
+-------------------+      +-----------------+
| K1 | K2 | K3      | ---> | P0 P1 P2 P3     |
+-------------------+      +-----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 탐색 및 갱신 | --> | 균형 상태 확인 | --> | 재구성 연산  | --> | 정합성 검증  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **탐색 및 갱신** — 루트부터 키를 비교하며 내려가 삽입 위치나 삭제 대상을 확정함
2. **균형 확인** — 연산 후 부모 노드로 거슬러 올라가며 높이 차($BF$)나 색상 규칙, 노드 채움률 위반 여부를 점검함
3. **재구성 수행** — 규칙 위반 시 단일/이중 회전(AVL, RB), 재색칠(RB), 또는 노드 분할/병합(B-Tree)을 실행함
4. **정합성 검증** — 재구성이 완료된 후 트리의 모든 경로가 정의된 균형 조건을 만족하는지 최종적으로 확인함

## Ⅵ. 실무 적용 및 유의점

1. 갱신이 집중되는 인메모리 색인에서는 Red-Black 트리로 회전 횟수를 줄이고 p95 갱신 지연과 회전 횟수로 적합성을 확인해야 함
2. DB 인덱스는 B-Tree 계열로 페이지 읽기 횟수와 트리 높이를 줄이고, 노드 분할 빈도와 p95 조회 지연으로 운영 적합성을 확인해야 함

## Ⅶ. 결론

- 트리 구조는 저장 위치와 조회·갱신 비율에 따라 AVL, Red-Black, B-Tree를 구분 선택해야 탐색 지연과 재구성 비용을 함께 통제할 수 있음
