## Ⅰ. 개요
- **정의**: Transformer 인코더를 적층하여 양방향 문맥을 동시에 학습하는 사전학습 언어 모델
- **배경/필요성**: 067 정적 임베딩은 동음이의어를 구분 못하며, 단방향 모델은 좌->우만 참조하여 문맥 이해가 불완전
- **비유**: 빈칸 채우기 시험을 반복 풀어 언어 전체를 이해한 범용 독해자

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인코더 양방향 어텐션 원리 | MLM·NSP 학습 목적 함수 차이 | 069 GPT(디코더, 자기 회귀)와 구조 혼동 시 감점 |

> 요약: Transformer 인코더 기반 양방향 학습으로 범용 자연어 이해(NLU) 능력을 사전 확보하는 모델임.

## Ⅱ. 구성요소
```text
+----------+   +-------------+   +----------+
| Token +  |-->| Transformer |-->| Task Head|
| Segment +|   | Encoder x12 |   | (MLM/CLS)|
| Position |   +------+------+   +----------+
+----------+          |
                +-----+------+
                |            |
           +----+---+  +----+---+
           |Self-Att|  |Feed-Fwd|
           +--------+  +--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Multi-Head Self-Attention | 입력 전체 토큰을 좌우 양방향으로 동시 참조하여 문맥 가중치 산출 | 360도 시야 |
| Feed-Forward Network | 어텐션 출력을 비선형 변환하여 표현력 확장 (d_ff = 3072) | 정보 정제기 |
| [CLS] / [MASK] 토큰 | 문장 표현 집약([CLS]) 및 마스킹 학습([MASK]) 용 특수 토큰 | 요약자/빈칸 |

> 요약: 셀프 어텐션과 FFN을 12층 적층하여 양방향 문맥 표현을 추출함.

## Ⅲ. 절차
```text
+----------+   +----------+   +----------+   +----------+
| Corpus   |-->| Masking  |-->| Pre-Train|-->| Fine-Tune|
+----------+   +----------+   +----------+   +----------+
```

1. **코퍼스 수집** — 위키백과·BookCorpus 등 대규모 비지도 텍스트를 확보(약 33억 단어)
2. **마스킹 구성** — 입력 토큰의 15%를 [MASK]로 치환하고, 문장 쌍에 [SEP]·[CLS] 삽입
3. **사전학습** — MLM(가려진 토큰 예측) + NSP(문장 연속성 판별) 목적 함수를 최소화
4. **파인튜닝** — 분류·NER·QA 등 하위 태스크의 소규모 지도 데이터로 출력 헤드만 재학습

> 요약: 마스킹 기반 양방향 사전학습 후, 태스크별 소규모 데이터로 파인튜닝하는 2단계 구조임.

## Ⅳ. 문제점
- **Pre-train/Fine-tune 불일치**: [MASK] 토큰이 파인튜닝·추론 시에는 등장하지 않아 학습 분포 괴리 발생
- **추론 지연**: BERT-Large 기준 파라미터 3.4억 개, 실시간 서비스에서 응답 지연 50ms 이상 발생
- **장문 처리 한계**: 최대 입력 512토큰, 셀프 어텐션 연산 복잡도 O(N^2)로 긴 문서 처리 불가

> 요약: 학습-추론 불일치·추론 지연·장문 한계가 실용화의 3대 병목임.

## Ⅴ. 개선방안
1. 단기: ELECTRA의 RTD(Replaced Token Detection) 방식으로 전환하여 [MASK] 불일치 해소
2. 중기: DistilBERT(지식 증류)로 파라미터 40% 감축, 추론 속도 60% 향상 달성
3. 장기: Longformer의 슬라이딩 윈도우 + 글로벌 어텐션으로 4096 토큰 이상 처리 가능

- **학습-추론 불일치**: [MASK] 분포 차이 -> RTD 방식 (지표: GLUE 스코어 동등 이상)
- **추론 지연**: 파라미터 비대 -> 증류·양자화 (지표: Latency < 10ms @batch=1)
- **장문 한계**: O(N^2) -> Sparse Attention (지표: 입력 길이 4096+ 처리)

> 요약: RTD 전환·증류 경량화·Sparse Attention으로 각 문제에 대응함.

## Ⅵ. 전망
- 향후 발전 방향: NLU 분야(문서 분류·검색·NER)에서 사실상 표준이며, 도메인 특화 BERT(BioBERT, FinBERT) 확산 지속
- 기술사적 판단: 069 GPT와 달리 텍스트 생성이 아닌 이해·분류에 최적화된 아키텍처로, 용도 구분이 핵심
- 기술사 제언: 생성이 불필요한 분류·검색 태스크에는 GPT 대비 BERT 계열이 비용 대비 실효적이므로, 태스크 특성에 따른 모델 선택을 권고함
