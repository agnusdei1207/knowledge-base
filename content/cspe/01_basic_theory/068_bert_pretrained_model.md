## 미리 알고가기

- 트랜스포머 인코더: 입력 토큰 전체를 양방향 어텐션으로 표현하는 구조임
- 셀프 어텐션: 문장 내 토큰 간 중요도를 계산하는 연산임
- 마스크 언어 모델링(MLM): 일부 토큰을 마스킹하고 양방향 문맥으로 원래 토큰을 예측하는 사전학습 과제임
- 다음 문장 예측(NSP): 두 번째 문장이 첫 번째 문장 뒤에 실제로 이어지는지 예측하는 사전학습 과제임
- 파인튜닝: 사전학습 모델을 특정 업무 데이터로 미세 조정하는 과정임
- 서브워드 분절(WordPiece): 빈도가 높은 문자열 조각을 어휘로 구성하는 방식임
- 정적 단어 임베딩·자기회귀 언어 모델(Word2Vec·GPT): 단어별 고정 벡터를 학습하는 방식과 다음 토큰을 생성하는 모델임
- 문장 대표 벡터([CLS]): 입력 전체를 대표하도록 문장 분류에 사용하는 BERT의 첫 토큰 표현임
- 모델 경량화: 모델 크기와 연산량을 줄여 제한된 장치에서도 실행하도록 만드는 작업임

## 작성 근거(검토용)

- **방향성**: BERT는 양방향 문맥으로 이해 과제의 정확도를 높이는 대신 인코더 구조상 직접 생성이 어렵고 입력 길이·추론 비용이 늘어나므로, 문맥 이해가 핵심인 업무에 적용하되 길이·지연 제약에 맞춰 운용해야 함
- **Ⅰ. 개요 구성**: BERT의 구조, 학습 방식, 활용 과제를 한 문장에 묶어 출제 키워드를 회수함
- **Ⅱ. 특징 선정**: 양방향 문맥·MLM·전이 활용·문맥별 임베딩을 서로 다른 판단 축으로 둠
- **Ⅲ. 비교축 선정**: 문맥 메커니즘·출력 범위·주요 리스크는 Word2Vec·GPT 대비 BERT의 고유 스펙이라 축은 유지하고, 업무 목적에 따른 선택 기준은 요약 문장의 구체적 분기 조건으로 명시함
- **Ⅳ. 구조 선정**: 토큰·세그먼트·위치 임베딩과 인코더·출력 헤드의 관계를 보여주도록 구성함
- **Ⅴ. 절차 선정**: 사전학습부터 파인튜닝까지 전이 흐름을 단계화함
- **Ⅵ. 사례 선정**: 입력 길이 제한과 추론 비용은 BERT 배포의 핵심 조건임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 본문에 쓰이지 않는 지표 정의를 정리했으며 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: BERT는 트랜스포머 인코더를 기반으로 양방향 문맥을 학습한 뒤 분류·독해·개체명 인식에 파인튜닝하는 사전학습 언어 모델임
- **배경/필요성**: 고정 벡터 모델과 단방향 생성 모델은 문맥에 따른 의미 변화를 반영하지 못하므로 양방향 사전학습 표현이 필요함

### 쉽게 이해하기 (학습용)
- 문장에서 한 단어를 가리고 앞뒤를 모두 읽은 뒤 빈칸을 채우는 퀴즈를 미리 잔뜩 풀어 두고, 그 실력을 여러 업무에 다시 써먹는 모델임

## Ⅱ. 특징

- 양방향 셀프 어텐션으로 좌우 문맥을 동시에 반영함
- 원형 BERT는 MLM으로 마스크 토큰을 복원하고 NSP로 문장 관계를 판정함
- 하나의 사전학습 백본을 여러 자연어 과제에 재사용함
- 문맥에 따라 같은 단어의 임베딩이 달라짐

### 쉽게 이해하기 (학습용)
- 빈칸 앞뒤 글을 동시에 읽고 정답을 유추함(양방향)
- 빈칸 채우기 퀴즈와 두 문장이 이어지는지 맞히는 퀴즈로 미리 훈련함
- 한번 훈련해둔 실력을 분류, 독해 등 여러 시험에 그대로 재사용함
- 같은 단어라도 앞뒤 문장이 다르면 그때그때 다른 뜻으로 읽어냄

## Ⅲ. 종류 및 비교

| 판단 기준 | Word2Vec | BERT | GPT |
|:---|:---|:---|:---|
| 문맥 메커니즘 | 고정 문맥 창 | 양방향 인코더 | 인과 디코더 |
| 출력 범위 | 고정 단어 벡터 | 문맥 토큰 벡터 | 다음 토큰 분포 |
| 주요 리스크 | 다의어 구분 불가 | 입력 길이 한계 | 사실 오류 생성 |

> 요약: 단어 단위 유사도만 필요하면 Word2Vec, 문맥 이해·분류가 필요하면 BERT, 텍스트 생성이 필요하면 GPT를 적용함.

### 쉽게 이해하기 (학습용)
- Word2Vec은 단어마다 고정된 뜻풀이 카드 한 장을 주고, BERT는 앞뒤 문장을 다 읽고서야 뜻풀이를 정해주며, GPT는 지금까지 읽은 글만 보고 다음에 올 말을 이어서 씀

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| WordPiece 토큰화 | 미등록어를 줄이는 서브워드 입력 |
| 입력 임베딩 | 토큰·세그먼트·위치 벡터의 합 |
| 인코더 스택 | 양방향 어텐션·피드포워드 반복 계층 |
| 출력 헤드 | 분류·독해·개체명 인식 출력층 |

> 요약: BERT는 WordPiece 입력에 토큰·세그먼트·위치 벡터를 더하고 인코더와 출력 헤드로 업무별 결과를 산출함.

```text
토큰 ID + 세그먼트 ID + 위치 ID
        -> 임베딩 합
        -> 트랜스포머 인코더 스택
        -> 문장 대표 벡터([CLS]) 또는 토큰 벡터
        -> 출력 헤드
```

### 쉽게 이해하기 (학습용)
- 단어 조각, 몇 번째 문장인지, 몇 번째 자리인지를 모두 표시(입력 임베딩)한 뒤 여러 겹 읽기 담당(인코더 스택)을 거쳐 문장 전체 요약본이나 단어별 이해를 만들고, 마지막에 업무에 맞는 담당자(출력 헤드)가 답을 냄

## Ⅴ. 원리 및 절차 흐름도

```text
사전학습 말뭉치 -> MLM/NSP 학습 -> 문맥 임베딩 -> 파인튜닝 -> 업무 적용
```

1. 대규모 말뭉치를 WordPiece 토큰으로 변환함
2. 일부 토큰을 양방향 문맥으로 복원하고 두 문장의 연결 관계를 판정함
3. 사전학습된 인코더가 문맥 벡터를 생성함
4. 업무별 데이터로 출력 헤드를 붙여 파인튜닝함
5. 파인튜닝된 모델을 분류·독해·개체명 인식 업무에 적용함

> 요약: BERT는 사전학습 인코더를 출력 헤드와 결합해 문맥 이해 모델로 전이함.

### 쉽게 이해하기 (학습용)
- 방대한 글로 빈칸 채우기와 문장 잇기 연습을 미리 해두고, 그렇게 익힌 읽기 실력에 업무별 마지막 답안지(출력 헤드)만 새로 붙여 짧게 더 훈련시킨 뒤 실제 업무에 씀

## Ⅵ. 실무 사례

1. 장문 문서 분류는 입력 길이를 넘는 문서를 겹치는 구간으로 나눠 BERT에 전달함
2. 모바일 문서 분류는 BERT를 증류·양자화해 단말에서 추론함

### 쉽게 이해하기 (학습용)
- 한 번에 다 읽지 못할 만큼 긴 글은 겹치게 나눠서 나눠 읽히고, 작은 기기에서 써야 할 때는 모델을 압축·경량화해 가볍게 만들어 씀

## Ⅶ. 결론

- BERT는 양방향 문맥 표현을 활용하는 과제에 적용하고 입력 길이와 추론 비용을 서비스 지연 한도에 맞춰야 함
- 장문은 무조건 잘라내지 말고 겹침 분할·장문 모델을 비교하며, 지연 한도를 넘으면 증류·양자화로 모델 크기를 낮춰야 함

### 쉽게 이해하기 (학습용)
- 앞뒤 문맥을 다 읽고 판단해야 하는 일에 적합하지만, 한 번에 읽을 수 있는 글 길이와 답을 내는 데 걸리는 시간을 서비스가 버틸 수 있는 수준에 맞춰야 함
