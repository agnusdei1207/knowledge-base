## 미리 알고가기

- 노드(Node): 실질적인 데이터 값과 인접 노드의 주소 또는 참조 정보를 포함하는 기본 저장 단위임
- 포인터(Pointer): 다른 노드의 위치를 가리키는 주소 또는 참조 정보로 노드 간 논리적 연결을 형성함
- 순차 접근(Sequential Access): 특정 위치의 데이터를 알기 위해 헤드부터 연결을 따라 순서대로 탐색해야 하는 방식임
- 불연속 할당: 데이터가 메모리상에 물리적으로 나란히 배치되지 않고 흩어져 있는 상태임

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 인접 노드를 가리키는 링크 정보를 함께 저장해, 물리적 배치와 무관하게 논리적 선형 순서를 유지하는 동적 자료구조임
- **배경/필요성**: 정적 배열은 선언 시 크기가 고정되어 메모리 낭비나 부족이 발생하고 중간 데이터 삽입·삭제 시 대량의 이동 비용이 들므로, 포인터 조작만으로 노드를 자유롭게 가감할 수 있는 유연한 구조가 필요함

## Ⅱ. 특징

- 연속 메모리 블록을 요구하지 않아 크기 변화에는 유연하지만, 불연속 배치로 캐시 지역성이 낮아질 수 있음
- 대상 위치를 찾은 뒤 새 노드와 기존 노드의 링크를 조정하면 데이터 이동 없이 삽입·삭제할 수 있음
- 임의 접근(Random Access)이 불가능하여 특정 위치를 조회하려면 반드시 $O(n)$의 순차 탐색이 필요하며 포인터 저장을 위한 추가 메모리가 소요됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 리스트 (Linked List) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|
| **메모리 할당** | 노드 단위로 불연속 메모리에 할당 | 연속된 메모리 블록 할당 및 재배치 |
| **조회 성능** | $O(n)$ (순차 탐색) | $O(1)$ (인덱스 임의 접근) |
| **삽입·삭제** | 위치 또는 이전 노드를 알고 있으면 $O(1)$, 탐색 포함 시 $O(n)$ | $O(n)$ (데이터 시프트 발생) |
| **캐시 효율** | 낮음 (불연속 배치로 공간 지역성 약함) | 높음 (연속 데이터 인출) |
| **추가 오버헤드** | 포인터 저장 공간 필요 | 배열 확장 시 일괄 복사 비용 |

> 요약: 데이터의 크기 변화가 잦고 중간 삽입·삭제가 빈번한 경우 연결 리스트가 유리하며, 조회가 주 목적인 경우 동적 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 사용자가 보관하고자 하는 실질적인 값이나 객체 정보를 담고 있음 |
| 링크/포인터 | 다음 또는 이전 노드의 주소나 참조를 저장하여 데이터 간의 논리적 순서를 연결함 |
| 헤드($Head$) | 리스트의 첫 번째 노드를 가리키는 진입점이며, 탐색이나 추가 작업의 기준이 됨 |
| 테일($Tail$) | 선택적으로 유지하는 마지막 노드 포인터이며, 리스트 끝 삽입을 빠르게 처리할 때 사용됨 |

```text
[ 단방향 연결 리스트 구조 ]
+------+      +---------------+      +---------------+      +------+
| Head | ---> | Data | Next --| ---> | Data | Next --| ---> | NULL |
+------+      +---------------+      +---------------+      +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 위치 탐색    | --> | 링크 조정     | --> | 참조 정리     | --> | 무결성 확인  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **위치 탐색** — 삽입 위치나 삭제 대상의 이전 노드까지 $Head$부터 순차적으로 이동함
2. **링크 조정** — 삽입 시에는 새 노드와 기존 노드의 링크를 연결하고, 삭제 시에는 이전 노드가 삭제 대상의 다음 노드를 가리키게 수정함
3. **참조 정리** — 삭제된 노드의 참조를 해제하거나 런타임이 회수할 수 있는 상태로 만들어 누수를 방지함
4. **무결성 확인** — $Head$, $Tail$, $NULL$ 경계가 올바른지 확인해 끊어진 링크나 순환 오류를 방지함

## Ⅵ. 실무 적용 및 유의점

1. 삽입·삭제 연산 자체는 $O(1)$이지만 실제 운영 환경에서는 위치 탐색 비용과 불연속 배치로 인한 캐시 지역성 저하가 더 클 수 있으므로 탐색이 빈번한 시스템에서는 배열이나 트리 구조를 우선 고려하고 조회 지연과 캐시 미스율로 확인해야 함
2. 노드 생성·해제가 잦은 시스템에서는 런타임의 메모리 관리 비용을 확인하고, 순회 종료 조건과 참조 해제 정책을 명확히 해 누수와 널 참조 오류를 방지해야 함

## Ⅶ. 결론

- 연결 리스트는 연속 메모리 확보 제약을 줄이고 중간 삽입·삭제를 단순화하지만 순차 접근 비용이 크므로, 조작 위치가 명확한 큐·덱·프리 리스트 같은 구조에 선별 적용해야 함
