## 미리 알고가기

- 노드: 데이터와 다음 노드의 위치 정보를 함께 가진 단위임
- 포인터: 다른 노드의 위치를 가리키는 연결 정보임
- 순차 접근: 앞에서부터 차례로 따라가야 원하는 위치에 도달하는 방식임
- 캐시 지역성: 가까운 메모리 주소를 연속해서 읽을 때 성능이 좋아지는 성질임

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 다음 노드의 연결 정보를 가지고, 노드 간 연결로 순서를 유지하는 선형 자료구조임
- **배경/필요성**: 배열은 중간 삽입과 삭제 때 뒤쪽 원소를 옮겨야 함. 연결 리스트는 노드 연결만 바꾸면 되므로 구조 변경이 잦은 데이터에 적합함

## Ⅱ. 특징

- 삽입과 삭제 위치를 알고 있으면 연결 정보만 바꿔 구조를 수정할 수 있음
- 크기를 미리 고정하지 않아도 노드를 동적으로 늘리거나 줄일 수 있음
- 특정 위치를 바로 찾지 못하므로 조회는 앞에서부터 따라가야 함
- 노드가 메모리에 흩어질 수 있어 반복 순회는 배열보다 불리할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 배열 | 연결 리스트 |
|:---|:---|:---|
| 위치 접근 | 인덱스로 바로 접근함 | 링크를 따라가야 함 |
| 중간 삽입·삭제 | 원소 이동이 필요함 | 연결 변경으로 처리함 |
| 메모리 배치 | 연속 공간이 필요함 | 비연속 공간을 사용할 수 있음 |
| 반복 순회 | 캐시 효율이 좋음 | 캐시 효율이 낮을 수 있음 |
| 적합한 상황 | 조회가 많은 데이터 | 삽입·삭제가 잦은 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 노드가 저장하는 실제 값임 |
| 링크 필드 | 다음 노드를 가리키는 연결 정보임 |
| 헤드 포인터 | 첫 노드를 가리키는 시작점임 |
| 보조 포인터 | 삽입과 삭제 중 이전 노드와 현재 노드를 추적함 |

```text
+------+     +-------------+     +-------------+     +------+
| Head | --> | data | next | --> | data | next | --> | NULL |
+------+     +-------------+     +-------------+     +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 위치 탐색 | --> | 이전 노드 확인 | --> | 링크 변경 | --> | 연결 확인 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 삽입하거나 삭제할 위치까지 링크를 따라감
2. 변경 대상의 이전 노드와 다음 노드를 확인함
3. 링크 값을 새 순서에 맞게 바꿈
4. 헤드와 마지막 노드가 올바른지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 위치 조회가 많은 데이터에는 연결 리스트보다 배열이나 해시 구조가 나은지 먼저 확인해야 함
2. 링크 갱신 순서를 잘못 잡으면 노드가 끊기거나 순환이 생기므로 삽입·삭제 후 순회 테스트로 연결을 확인해야 함

## Ⅶ. 결론

- 연결 리스트는 삽입과 삭제가 잦을 때 유리하지만, 순차 접근 비용과 캐시 효율 저하를 함께 고려해야 함
