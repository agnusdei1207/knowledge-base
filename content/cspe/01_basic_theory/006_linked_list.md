## 미리 알고가기

- 노드: 데이터와 다음 위치 정보로 구성된 저장 단위임
- 포인터 재연결: 원소 이동 없이 링크만 바꿔 구조를 수정하는 방식임
- 캐시 지역성: 인접 메모리 접근이 많을수록 유리한 성질이며 연결 리스트는 이 점이 약함

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 다음 노드 참조를 보유해 물리적 메모리 연속성 없이도 논리적 순서를 유지하는 동적 선형 자료구조임
- **배경/필요성**: 배열은 중간 삽입과 삭제 시 대량 이동이 필요하므로, 변경이 잦은 데이터 흐름에서는 포인터 재연결만으로 구조를 바꾸는 방식이 더 실용적임

## Ⅱ. 특징

- 삽입과 삭제는 기준 노드 위치만 알면 포인터 변경으로 빠르게 처리할 수 있음
- 메모리를 실행 중에 유연하게 확장할 수 있어 크기를 미리 고정하기 어려운 업무에 적합함
- 임의 접근이 불가능해 특정 위치 탐색은 순차적으로 진행해야 하므로 조회 중심 업무에는 불리함
- 노드가 흩어져 저장되기 쉬워 캐시 효율과 메모리 사용량 측면에서 배열보다 손해를 보기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 배열 | 연결 리스트 |
|:---|:---|:---|
| 접근 방식 | 임의 접근 $O(1)$ | 순차 접근 $O(n)$ |
| 중간 삽입/삭제 | 원소 이동 필요 | 포인터 재연결 중심 |
| 메모리 배치 | 연속 공간 필요 | 비연속 공간 허용 |
| 캐시 효율 | 높음 | 낮음 |
| 적합 업무 | 조회 중심 | 갱신 중심 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| 데이터 필드 | 실제 저장 값임 | 업무 데이터 구조와 결합됨 |
| 링크 필드 | 다음 노드 주소를 저장함 | 구조 유지의 핵심임 |
| 헤드 포인터 | 첫 노드 시작점임 | 공백 리스트와 첫 삽입 처리 기준임 |
| 보조 포인터 | 현재, 이전, 다음 노드를 추적함 | 삭제와 삽입 구현 안정성에 영향 줌 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 위치탐색 | --> | 링크조정 | --> | 노드연결 | --> | 무결성확인 |
+----------+     +----------+     +----------+     +----------+
```

1. **위치탐색**: 삽입 또는 삭제 기준 노드까지 순차 이동함
2. **링크조정**: 이전 노드와 다음 노드 연결 방향을 계산함
3. **노드연결**: 새 노드를 끼워 넣거나 대상 노드를 제거함
4. **무결성확인**: 헤드 갱신, 널 포인터, 길이 정보가 맞는지 확인함

## Ⅵ. 문제점 및 해결 방안

1. **탐색 비용이 누적됨**: 위치를 찾는 과정이 길어지면 전체 성능이 선형으로 악화됨
   - **해결 방안**: 조회 비중이 높은 구간은 배열, 해시, 트리로 구조를 전환함 (확인: 평균 탐색 길이)
2. **포인터 오류가 치명적임**: 링크 하나만 잘못 갱신해도 노드 유실이나 순환 구조가 발생함
   - **해결 방안**: 헤드, 꼬리, 단일 노드, 공백 리스트 테스트를 분리해 검증함 (확인: 경계 케이스 테스트)
3. **캐시 비효율이 큼**: 메모리 파편화로 인해 반복 순회 성능이 떨어질 수 있음
   - **해결 방안**: 노드 풀이나 연속 할당 전략을 도입해 지역성을 높임 (확인: 캐시 미스율, 순회 시간)

## Ⅶ. 적용 사례

- 운영체제 커널: 빈번한 삽입과 삭제가 발생하는 대기열 관리에 사용함, 확인 지표는 삽입 지연시간과 구조 무결성임
- 메모리 관리자: 자유 블록 목록을 연결해 가변 크기 공간을 관리함, 확인 지표는 할당 실패율과 단편화율임
- 스트림 처리 버퍼: 순차 소비와 동적 확장이 필요한 구간에 적용함, 확인 지표는 처리량과 메모리 재할당 횟수임

## Ⅷ. 결론

연결 리스트는 조회 성능보다 구조 변경 비용을 줄이는 데 목적이 있는 자료구조이므로, 탐색 빈도보다 삽입과 삭제 빈도가 높은 구간에서 선택해야 함.
