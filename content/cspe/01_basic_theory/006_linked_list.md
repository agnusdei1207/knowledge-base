## 미리 알고가기

- 노드(Node): 실질적인 데이터 값과 다음 노드의 메모리 주소 정보를 포함하는 기본 저장 단위임
- 포인터(Pointer): 다른 노드가 위치한 메모리 물리 주소를 가리켜 논리적인 연결을 형성하는 정보임
- 순차 접근(Sequential Access): 특정 위치의 데이터를 알기 위해 헤드부터 연결을 따라 순서대로 탐색해야 하는 방식임
- 불연속 할당: 데이터가 메모리상에 물리적으로 나란히 배치되지 않고 흩어져 있는 상태임

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 다음 노드를 가리키는 포인터를 가져, 물리적 메모리 위치에 상관없이 논리적 선형 관계를 유지하는 동적 자료구조임
- **배경/필요성**: 정적 배열은 선언 시 크기가 고정되어 메모리 낭비나 부족이 발생하고 중간 데이터 삽입·삭제 시 대량의 이동 비용이 들므로, 포인터 조작만으로 노드를 자유롭게 가감할 수 있는 유연한 구조가 필요함

## Ⅱ. 특징

- 배열과 달리 불연속적인 메모리 공간에 노드를 동적으로 할당하므로 사전에 최대 크기를 정할 필요가 없으며 메모리 단편화 영향을 덜 받음
- 특정 노드를 삭제하거나 새 노드를 삽입할 때 데이터를 밀어내거나 당기는 과정 없이 이전 노드의 포인터 주소값만 변경하면 되어 갱신 비용이 저렴함
- 임의 접근($Random$ $Access$)이 불가능하여 특정 위치를 조회하려면 반드시 $O(n)$의 순차 탐색이 필요하며 포인터 저장을 위한 추가 메모리가 소요됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 리스트 (Linked List) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|
| **메모리 할당** | 힙($Heap$)에 불연속적으로 동적 할당 | 연속된 메모리 블록 할당 및 재배치 |
| **조회 성능** | $O(n)$ (순차 탐색) | $O(1)$ (인덱스 임의 접근) |
| **삽입·삭제** | $O(1)$ (포인터 갱신, 탐색 제외) | $O(n)$ (데이터 시프트 발생) |
| **캐시 효율** | 낮음 (메모리 파편화) | 높음 (연속 데이터 인출) |
| **추가 오버헤드** | 포인터 저장 공간 필요 | 배열 확장 시 일괄 복사 비용 |

> 요약: 데이터의 크기 변화가 잦고 중간 삽입·삭제가 빈번한 경우 연결 리스트가 유리하며, 조회가 주 목적인 경우 동적 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 사용자가 보관하고자 하는 실질적인 값이나 객체 정보를 담고 있음 |
| 링크/포인터 | 다음 또는 이전 노드의 물리 메모리 주소를 저장하여 데이터 간의 논리적 순서를 연결함 |
| 헤드($Head$) | 리스트의 첫 번째 노드를 가리키는 진입점이며, 탐색이나 추가 작업의 기준이 됨 |
| 테일($Tail$) | 리스트의 마지막 노드를 가리키며, 리스트 끝에 데이터를 즉시 추가할 때 사용됨 |

```text
[ 단방향 연결 리스트 구조 ]
+------+      +---------------+      +---------------+      +------+
| Head | ---> | Data | Next --| ---> | Data | Next --| ---> | NULL |
+------+      +---------------+      +---------------+      +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 위치 탐색    | --> | 새 노드 생성  | --> | 포인터 연결   | --> | 이전 연결 해제|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **위치 탐색** — 데이터를 삽입하거나 삭제할 대상 노드의 앞쪽 노드까지 $Head$부터 순차적으로 이동함
2. **노드 생성** — (삽입 시) 새로운 데이터를 담은 노드를 동적으로 생성하고 값을 할당함
3. **포인터 연결** — 새 노드의 $Next$ 포인터가 다음 노드를 가리키게 하고, 이전 노드의 $Next$ 포인터가 새 노드를 가리키게 수정함
4. **연결 해제** — (삭제 시) 이전 노드의 포인터를 삭제할 노드의 다음 노드로 직접 연결하여 논리적 고리에서 제외함

## Ⅵ. 실무 적용 및 유의점

1. 삽입·삭제 연산 자체는 $O(1)$이지만 실제 운영 환경에서는 해당 위치를 찾는 순차 탐색 비용과 메모리 파편화로 인한 캐시 미스 오버헤드가 더 클 수 있으므로 탐색이 빈번한 시스템에서는 배열이나 트리 구조를 우선 고려해야 함
2. 노드의 동적 생성과 소멸이 반복되면 가비지 컬렉션($GC$) 부담이 증가하거나 메모리 누수가 발생할 수 있으므로, 재사용 가능한 노드를 미리 확보하는 객체 풀링($Pooling$) 기법을 검토하고 종료 지점의 널 포인터($Null$ $Pointer$) 예외를 통제해야 함

## Ⅶ. 결론

- 연결 리스트는 메모리의 물리적 한계를 극복하고 동적인 구조 변경에 최적화된 필수 자료구조이나 순차 접근의 비효율성이 존재하므로, 큐나 덱처럼 조작 지점이 명확한 환경에서 그 효용을 극대화해야 함
