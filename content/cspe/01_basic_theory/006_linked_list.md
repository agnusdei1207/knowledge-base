# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 연결 리스트는 데이터와 다음 노드의 메모리 주소(포인터)를 함께 저장하는 노드(Node)들이 사슬처럼 이어진 **포인터 기반 동적 선형 자료구조**다. 배열과 함께 가장 기본적인 두 선형 자료구조 중 하나다.
- **왜 필요한가**: 배열은 생성 시점에 연속된 메모리 블록을 통째로 확보해야 하고, 중간에 원소를 넣거나 빼려면 뒤 원소를 전부 밀어야(Shift) 한다. 연결 리스트는 흩어진 메모리 조각을 포인터로 이어붙여, 크기를 실행 중에 자유롭게 늘리고 삽입·삭제를 포인터 조작만으로 끝낸다.
- **핵심 직관**: 보물찾기 쪽지 릴레이다. 첫 쪽지(Head)를 열어야 다음 쪽지 위치를 알 수 있고, 그 쪽지를 열어야 또 다음 위치를 안다 — 순서대로 하나씩만 따라갈 수 있다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 선형 자료구조 | 원소가 하나의 순서열로 나열되는 자료구조 | 한 줄로 선 사람들 |
| 동적 자료구조 | 크기가 고정되지 않고 실행 중에 늘고 주는 자료구조 | 신축 가능한 옷 |
| 노드(Node) | 데이터 필드 + 포인터 필드로 구성된 하나의 저장 단위 | 보물찾기 쪽지 한 장 |
| 헤드(Head) | 리스트 순회의 유일한 진입점, 첫 노드를 가리키는 포인터 | 첫 번째 쪽지가 있는 곳 |
| 이중 연결 리스트 | 각 노드가 이전·다음 노드를 모두 가리키는 리스트 | 양방향 화살표 사슬 |

## 깊이 이해
- **배경·문제의식**: 연속적인 메모리 할당을 요구하는 배열은 중간 데이터 삽입/삭제 시 대량의 메모리 이동이 발생하여 성능이 크게 저하된다.
- **작동 원리**: 데이터를 담은 독립된 노드들이 자신의 다음 노드 위치(포인터)만 기억하여 서로 연결된다. 삽입/삭제 시 포인터의 방향만 바꿔주면 되므로 물리적 데이터 이동이 없다.
- **비유**: 기차의 객차들을 연결 고리로 이어놓은 것과 같다. 중간에 새 객차를 넣으려면 앞뒤 고리만 풀어서 새 객차에 연결하면 된다.
- **구체 예시**: 1,000만 개 데이터 중간에 1개를 넣을 때, 배열은 최대 1,000만 번의 이동이 필요하지만 연결 리스트는 포인터 교체 2번(O(1))으로 끝난다(단, 위치를 알고 있을 때).
- **흔한 오해·주의점**: "연결 리스트는 삽입이 무조건 O(1)이다"라고 오해하기 쉽지만, 삽입할 '위치를 찾는 탐색' 과정 자체는 O(N)이 소요된다.

## 연결 개념
- **007 스택·큐·덱**: 연결 리스트를 내부 구현체로 사용하는 대표 자료구조
- **배열(Array)**: 연속 메모리 기반의 대조 구조, 탐색 O(1) vs 삽입 O(1)의 상호 트레이드오프

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터와 메모리 주소(포인터)를 하나로 묶은 노드들의 체이닝을 통해 논리적 연속성을 구현한 동적 자료구조이다.
> 2. **가치**: 크기 가변성과 O(1)의 삽입/삭제 오버헤드를 제공하여 빈번한 데이터 갱신이 일어나는 동적 메모리 환경에 적합하다.
> 3. **판단 포인트**: 특정 인덱스 고속 접근(Random Access)이 불가하므로, 조회 중심은 배열을, 갱신 중심 버퍼는 연결 리스트를 채택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열 한계 극복 원리 확인 | 물리적 불연속성과 논리적 연속성 분리 | 탐색 성능이 배열보다 우수하다는 단정 |
| 자료구조 선택 기준 제시 | 탐색 지연(O(N)) 및 포인터 오버헤드 | 종류(단일/이중)만 단순 나열하는 서술 |

> 요약: 메모리 제약을 극복하고 쓰기(Write) 효율을 높이는 대신, 순차 탐색 비용과 포인터 메모리를 희생하는 극단적 Trade-off 구조다.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터 필드와 포인터 필드로 구성된 노드들이 체인 형태로 이어져 논리적 연속성을 갖는 동적 선형 자료구조
- 배경: 연속 메모리 블록을 요구하는 배열의 단편화 한계 및 중간 삽입/삭제 시 발생하는 밀어내기 연산 병목 발생
- 필요성: 시스템 버퍼, 해시 충돌 체이닝 등 크기 예측이 불가능한 동적 데이터 집합을 밀리초 내 관리하기 위해 필수

---

## Ⅱ. 구조 및 구성요소

```text
Head -> [ Data | Next ] -> [ Data | Next ] -> [ Data | Null ]
           (Node 1)           (Node 2)           (Node N)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드 (Node) | 데이터와 다음 포인터를 담는 기본 블록 | 런타임에 동적 할당 |
| 데이터 필드 | 실제 값(Value) 보관 공간 | 다양한 타입 수용 |
| 포인터 필드 | 다음 노드의 물리적 메모리 주소 저장 | 이중 연결 시 Prev 추가 |
| 헤드 (Head) | 연결 리스트 탐색의 유일한 진입점 | 소실 시 전체 순회 불가 |

> 요약: 노드는 흩어진 메모리에 배치되며, 포인터의 논리적 릴레이를 통해서만 인덱스 순서가 성립된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 수신 -> 삽입 위치 탐색 -> 신규 노드 동적 할당 -> 포인터 링크 재배치 -> 삽입 완료
```

- 1단계 [위치 탐색]: Head부터 O(N) 순차 탐색하여 삽입 기준점 노드 확보
- 2단계 [동적 할당]: OOM(Out of Memory) 방지 하에 신규 노드 메모리 획득
- 3단계 [포인터 갱신]: 신규 노드의 Next 포인터가 다음 노드를 가리키도록 연결
- 4단계 [연결 확정]: 이전 노드의 Next 포인터가 신규 노드를 가리키도록 재배치 완료

> 요약: 노드 연결은 O(1) 연산이나, 정확한 링크 갱신을 위해 O(N) 탐색 비용이 선행된다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 삽입/삭제 시 데이터 이동(Shift) 오버헤드 부재 | 데이터 갱신 빈도 |
| 한계 | 인덱스 기반 특정 위치 랜덤 접근 불가 | 데이터 조회 빈도 |
| 메모리 | 런타임 동적 할당으로 미사용 공간 낭비 방지 | 가용 메모리 단편화 상태 |

> 요약: 공간 낭비 없이 런타임 확장이 가능하나, 임의 접근 시 O(N) 탐색 지연이 강제된다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 배열 (Array) | 연결 리스트 (Linked List) | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 접근 | 인덱스 랜덤 접근 O(1) | 헤드부터 순차 탐색 O(N) | 데이터 조회가 90% 이상인 경우 |
| 삽입/삭제 | 데이터 밀어내기 최대 O(N) | 포인터 갱신 O(1) | 빈번한 요소 교체 여부 |
| 오버헤드 | 고정 크기에 따른 미사용 낭비 | 포인터 보관을 위한 추가 메모리 | 데이터 크기 대비 포인터 비용 |

> 요약: 빈번한 데이터 추가/제거가 일어나는 큐 시스템은 리스트를, 고속 인덱스 조회가 필요한 통계 시스템은 배열을 채택한다.

**리스크·대응:**
- 단방향 탐색 지연: 이전 노드 역추적 불가 → Prev 포인터를 추가한 이중 연결 리스트(Doubly)로 튜닝 (지표: 역방향 조회 처리량)
- 캐시 지역성 저하: 노드 불연속 할당에 따른 캐시 미스 → 다수 노드를 블록화한 Unrolled Linked List 적용 (지표: 캐시 적중률)
- 꼬리 갱신 병목: 마지막 노드 탐색 부하 → 마지막을 가리키는 Tail 포인터 유지 또는 환형 구조 도입 (지표: 끝단 갱신 응답 시간)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LRU 캐시 교체 알고리즘 구현: 해시 테이블(고속 조회)과 이중 연결 리스트(순서 관리)를 결합하여 O(1) 단위 축출 아키텍처 설계
2. 해시 충돌 체이닝 방어: 키 해시 값이 일치하는 잉여 레코드를 연결 리스트로 매달아 해시 테이블 붕괴 원천 차단
3. 스케줄러 Ready Queue 구성: OS 프로세스 스케줄링 시 가변적인 태스크를 동적 큐(연결 리스트 기반)로 관리하여 메모리 최적화

**결론 (2줄):**
- 기술사 판단: 연결 리스트는 삽입 효율이 뛰어나나 CPU 캐시 지역성에 불리하므로, 최신 아키텍처에서는 가변 배열과 벤치마크 후 채택해야 한다.
- 향후 방향: 대용량 분산 시스템에서는 포인터 참조 한계 극복을 위해 로그 구조화(Log-structured) 또는 압축 배열이 보완재로 부상하고 있다.
