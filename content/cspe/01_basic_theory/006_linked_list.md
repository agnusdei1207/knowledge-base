## 미리 알고가기

- 노드(Node): 데이터와 다음 링크, 유형에 따라 이전 링크를 저장하는 기본 단위임
- 링크·포인터(Link/Pointer): 다음 또는 이전 노드 위치를 가리켜 논리 순서를 만드는 참조임
- 순차 접근(Sequential Access): 헤드부터 링크를 따라 목표 위치까지 이동하는 방식임
- 불연속 할당: 노드가 메모리상에 연속 배치되지 않고 흩어져 저장되는 방식임
- 더미 노드(Dummy Node): 경계 처리를 단순화하기 위해 실제 값 없이 두는 보조 노드임
- 최근 미사용 캐시(LRU Cache): 가장 오래 사용하지 않은 항목부터 제거하도록 접근 순서를 관리하는 캐시임

## 작성 근거(검토용)

- **방향성**: 연결 리스트는 위치를 이미 알고 있는 삽입·삭제를 링크 교체만으로 처리하는 대신 임의 위치 조회에는 $O(n)$ 순차 탐색이 들므로, 갱신 경로가 이미 정해진 업무에만 쓰고 조회가 잦으면 배열·트리로 전환해야 함
- **개요 구성**: 불연속 저장과 논리 순서 유지를 함께 설명해 배열과의 차이를 정의에서 분리함
- **Ⅱ. 특징 선정**: 노드 할당, 이전 노드 기반 갱신, 순차 탐색, 캐시 지역성은 선택 기준을 직접 만듦
- **Ⅲ. 비교축 선정**: 저장 구조, 위치 조회 비용, 중간 갱신 비용은 연결 리스트와 동적 배열의 선택을 가름
- **Ⅳ. 구조 선정**: Head에서 링크를 따라 NULL까지 이동하는 구조가 순차 접근 비용의 원인이므로 포함함
- **Ⅴ. 절차 선정**: 위치 탐색·링크 교체·참조 정리·경계 확인 순서가 삽입·삭제의 실제 비용과 오류 지점을 보여주므로 절차로 둠
- **Ⅵ. 실무 사례 선정**: LRU는 연결 리스트와 해시 테이블을 함께 써야 단건 접근과 순서 갱신을 모두 $O(1)$로 유지하므로 결합 구조를 명시함
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 위치 조회·갱신 비용 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 데이터 노드를 포인터로 연결해 물리적으로 흩어진 저장 공간에서도 논리적 순서를 유지하는 동적 선형 자료구조임
- **배경/필요성**: 중간 삽입·삭제의 원소 이동을 줄이기 위해 링크만 바꾸는 동적 구조가 필요함

### 쉽게 이해하기 (학습용)
- 보물찾기 쪽지처럼 각 칸이 다음 칸 위치만 가리켜, 쪽지들이 방 여기저기 흩어져 있어도 순서대로 따라가면 됨

## Ⅱ. 특징

- 노드 단위 할당은 연속 메모리 블록을 요구하지 않음
- 대상의 이전 노드를 알면 링크 변경만으로 삽입·삭제를 처리함
- 임의 인덱스 접근이 없어 목표 위치 조회는 $O(n)$ 순차 탐색임
- 낮은 캐시 지역성이 조회 지연을 키우며 포인터 저장 공간도 추가 메모리 비용을 만듦

### 쉽게 이해하기 (학습용)
- 쪽지가 방 어디에 흩어져 있어도 상관없이 다음 칸 위치만 적어두면 됨
- 끼워 넣을 자리 바로 앞 쪽지만 알면 화살표만 바꿔 새 쪽지를 끼울 수 있음
- 몇 번째 쪽지인지 알려면 처음부터 화살표를 따라가야 해서 한 번에 건너뛸 수 없음

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 리스트 (Linked List) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|
| **저장 방식** | 노드 단위 불연속 할당 | 연속 메모리 블록 할당 |
| **위치 조회** | 링크 순회로 $O(n)$ | 인덱스 접근으로 $O(1)$ |
| **중간 갱신** | 이전 노드를 알고 있으면 $O(1)$ | 원소 이동으로 $O(n)$ |

> 요약: 이전 노드를 확보한 중간 갱신은 연결 리스트, 인덱스 조회는 동적 배열이 적합함.

### 쉽게 이해하기 (학습용)
- 화살표를 따라가야 원하는 자리를 찾는 방식(연결 리스트)과 몇 번째 칸인지 번호만 보면 바로 찾는 방식(동적 배열)은 찾는 속도와 끼워 넣는 속도가 서로 반대로 유리함

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 필드 | 노드가 보관하는 값 또는 객체 참조 |
| 링크 필드 | 다음 노드 또는 이전·다음 노드를 연결하는 논리 순서 참조 |
| 헤드(Head) | 첫 노드를 가리키는 탐색 진입점 |
| 종단 표시 | 마지막 링크가 가리키는 NULL 또는 순환 구조의 헤드 |

```text
[ 단방향 연결 리스트 구조 ]
+------+      +---------------+      +---------------+      +------+
| 헤드 | ---> | 데이터 | 다음 --| ---> | 데이터 | 다음 --| ---> | NULL |
+------+      +---------------+      +---------------+      +------+
```

> 요약: 연결 리스트는 링크가 논리 순서를 만들지만 목표 위치까지는 순차 접근해야 함.

### 쉽게 이해하기 (학습용)
- 각 쪽지에 적힌 내용(데이터 필드)과 다음 쪽지 위치(링크 필드), 첫 쪽지를 가리키는 표지판(헤드), 마지막 쪽지임을 알리는 표시(종단)가 모여 하나의 줄을 이룸

## Ⅴ. 원리 및 절차 흐름도

```text
대상 위치 탐색 → 선행·후행 노드 확인 → 링크 교체
                                      ↓
                           제거 노드 참조 정리
                           ├─ 경계 노드 → 헤드·테일 갱신
                           └─ 내부 노드 → 연결 정합성 확인
```

1. **위치 탐색**: $Head$부터 갱신 대상의 이전 노드까지 이동함
2. **링크 교체**: 삽입·삭제 지점의 인접 노드 링크를 갱신함
3. **참조 정리**: 삭제 노드 참조를 해제해 누수와 잘못된 접근을 방지함
4. **경계 확인**: $Head$, $Tail$, $NULL$ 또는 더미 노드 연결을 확인함

> 요약: 삽입·삭제는 링크 교체보다 위치 탐색과 경계 정합성에서 비용과 오류가 생김.

### 쉽게 이해하기 (학습용)
- 원하는 자리 바로 앞 쪽지까지 순서대로 걸어가서, 앞뒤 화살표만 바꿔 끼우거나 빼고, 마지막에 첫 쪽지·끝 쪽지 표시가 어긋나지 않았는지 확인하는 순서임

## Ⅵ. 실무 사례

1. LRU 캐시는 해시로 항목을 찾고 이중 연결 리스트에서 최근 사용 순서를 갱신함

### 쉽게 이해하기 (학습용)
- 최근에 만진 물건을 앞쪽에 두고 오래 안 쓴 물건을 뒤로 밀어내는 정리함처럼, 어디 있는지는 색인(해시)으로 바로 찾고 순서는 줄(연결 리스트)로 관리함

## Ⅶ. 결론

- 연결 리스트는 링크만 바꿔 삽입·삭제하기 쉽지만, 원하는 위치를 찾는 비용과 포인터 오류를 고려해야 함
- 위치를 이미 알고 있는 갱신 경로에는 적합하지만 임의 조회가 많은 업무는 배열·트리로 전환해 탐색 비용을 줄여야 함

### 쉽게 이해하기 (학습용)
- 어디 끼울지 이미 알고 있으면 화살표만 바꿔 금방 끝나지만, 몇 번째 쪽지인지부터 매번 찾아야 한다면 번호로 바로 찾는 방식으로 바꾸는 게 나음
