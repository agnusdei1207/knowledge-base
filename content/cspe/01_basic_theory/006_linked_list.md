## 미리 알고가기

- 노드(Node): 데이터와 다음·이전 링크를 함께 저장하는 기본 단위임
- 링크/포인터(Link/Pointer): 다음 또는 이전 노드 위치를 가리켜 논리 순서를 만드는 참조임
- 순차 접근(Sequential Access): 헤드부터 링크를 따라 목표 위치까지 이동하는 방식임
- 불연속 할당: 노드가 메모리상에 연속 배치되지 않고 흩어져 저장되는 방식임
- 더미 노드(Dummy Node): 경계 처리를 단순화하기 위해 실제 값 없이 두는 보조 노드임

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 데이터 노드를 포인터로 연결해 물리적으로 흩어진 저장 공간에서도 논리적 순서를 유지하는 동적 선형 자료구조임
- **배경/필요성**: 배열은 중간 삽입·삭제 때 원소 이동이 크므로 삽입·삭제 위치를 이미 알면 링크만 바꾸는 구조가 필요함

## Ⅱ. 특징

- 노드 단위 할당으로 연속 메모리 확보 실패에 덜 민감함
- 대상의 이전 노드를 알면 링크 변경만으로 삽입·삭제를 처리함
- 임의 인덱스 접근이 없어 목표 위치 조회는 $O(n)$ 순차 탐색임
- 포인터 저장 공간과 낮은 캐시 지역성이 조회 지연을 키움

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 리스트 (Linked List) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|
| **저장 방식** | 노드 단위 불연속 할당 | 연속 메모리 블록 할당 |
| **조회** | $O(n)$, 링크 순차 탐색 | $O(1)$, 인덱스 직접 접근 |
| **삽입·삭제** | 위치 파악 후 $O(1)$ | 중간 갱신 시 $O(n)$ 이동 |
| **캐시 지역성** | 낮음, 포인터 추적으로 분산 접근 | 높음, 연속 데이터 접근 |
| **주요 비용** | 포인터 공간, 탐색 지연 | 확장 시 재할당·복사 |

> 요약: 위치가 알려진 갱신은 연결 리스트가 유리하고, 조회 중심 구조는 동적 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 저장 대상 값이나 객체 참조를 담고 실제 업무 데이터를 표현함 |
| 링크/포인터 | 다음 또는 이전 노드를 가리켜 메모리 불연속성을 논리 순서로 보정함 |
| 헤드($Head$) | 첫 노드를 가리키는 탐색 진입점이며 빈 리스트 판정 기준이 됨 |
| 테일($Tail$) | 끝 삽입 지연을 줄이지만 삭제·갱신 시 정합성 관리가 필요함 |
| 더미 노드 | 첫 삽입·마지막 삭제 같은 경계 처리를 단순화함 |

```text
[ 단방향 연결 리스트 구조 ]
+------+      +---------------+      +---------------+      +------+
| Head | ---> | Data | Next --| ---> | Data | Next --| ---> | NULL |
+------+      +---------------+      +---------------+      +------+
```

> 요약: 연결 리스트는 링크가 논리 순서를 만들지만 목표 위치까지는 순차 접근해야 함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 위치 탐색    | --> | 링크 교체    | --> | 참조 정리    | --> | 경계 확인    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **위치 탐색**: $Head$부터 갱신 대상의 이전 노드까지 이동함
2. **링크 교체**: 삽입 노드나 삭제 대상의 앞뒤 링크를 바꿈
3. **참조 정리**: 삭제 노드 참조를 해제해 누수와 잘못된 접근을 방지함
4. **경계 확인**: $Head$, $Tail$, $NULL$ 또는 더미 노드 연결을 확인함

> 요약: 삽입·삭제는 링크 교체보다 위치 탐색과 경계 정합성에서 비용과 오류가 생김.

## Ⅵ. 실무 적용 및 유의점

1. LRU 캐시는 해시 테이블로 노드 포인터를 함께 보관해야 $O(1)$ 갱신이 유지되므로 적중률·노드 누락 테스트로 확인함
2. 조회 중심 컬렉션은 연결 리스트가 순차 탐색 병목을 만들므로 배열·트리와 비교하고 p95 조회 지연으로 검증함

## Ⅶ. 결론

- 연결 리스트는 위치가 명확한 삽입·삭제에 적합하며, 조회 지연·포인터 정합성·캐시 지역성을 함께 검증해야 함

## 작성 근거(검토용)

- **개요 구성**: 불연속 저장과 논리 순서 유지를 함께 설명해 배열과의 차이를 정의에서 분리함
- **특징 선정**: 노드 할당, 이전 노드 기반 갱신, 순차 탐색, 캐시 저하는 선택 기준을 직접 만듦
- **Ⅲ 비교축**: 동적 배열과 비교해 조회 중심인지 갱신 중심인지 판단하게 함
- **구조 도식**: Head에서 링크를 따라 NULL까지 이동하는 구조가 순차 접근 비용의 원인이므로 포함함
- **실무 유의점**: LRU는 연결 리스트 장점이 해시 포인터와 결합될 때만 살아나므로 함께 명시함
