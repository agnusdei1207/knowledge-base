# 📖 【암기용】 개념 완전 이해

> 목적: 연결 리스트를 처음 보는 사람도 배열과의 차이, 포인터 연결 원리, 적용 기준을 이해하게 만든다.

## 한눈에
- **개요**: 노드가 데이터와 다음 위치 참조를 함께 저장하는 선형 자료구조
- **왜 필요한가**: 배열의 중간 삽입·삭제는 원소 이동 O(n)이지만, 연결 리스트는 선행 노드 확보 시 포인터 변경 O(1)임
- **핵심 직관**: 칸 번호로 찾는 배열이 아니라, 각 칸이 다음 칸 주소를 들고 줄을 잇는 구조임

## 깊이 이해
- **배경·문제의식**: 배열은 연속 메모리와 재할당 비용이 필요함. 연결 리스트는 흩어진 노드를 포인터로 연결해 크기 변화를 흡수함
- **작동 원리**: Head가 첫 노드를 가리키고, 각 노드의 next가 다음 노드를 가리킴. 삽입은 선행 노드의 next를 새 노드로 바꾸고, 삭제는 삭제 대상 앞뒤 노드를 직접 연결함
- **비유**: 지하철 좌석 번호표가 아니라, 사람이 다음 사람 연락처를 들고 있는 대기열과 같음
- **구체 예시**: 단일 연결 리스트에서 Head 뒤 삽입은 포인터 2회 변경으로 O(1), 1,000번째 노드 탐색은 처음부터 1,000회 순회로 O(n)
- **흔한 오해·주의점**: "삽입·삭제가 항상 O(1)"은 선행 노드를 이미 알고 있을 때만 성립함. 위치 탐색까지 포함하면 O(n)임

## 연결 개념
- 배열(Array) — 임의 접근 O(1) 비교 대상 / 스택·큐 — 연결 리스트 구현 ADT / 해시 체이닝 — 충돌 버킷 구성

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 연결 리스트는 노드가 데이터와 참조 포인터를 보유하고 순서를 포인터 연결로 표현하는 선형 자료구조이다.
> 2. **가치**: 중간 삽입·삭제는 선행 노드 확보 시 O(1), 임의 접근은 Head부터 순회하므로 O(n)이다.
> 3. **판단 포인트**: 접근 빈도가 높으면 배열, 삽입·삭제와 크기 변동이 많으면 연결 리스트를 선택한다.

---

## Ⅰ. 개요 및 필요성

연결 리스트는 노드 간 참조로 순서를 표현한다. 배열은 크기 변경·중간 삭제 시 원소 이동이 발생한다. 연결 리스트는 포인터 재배치로 큐·스택·체이닝 버킷 구현에 적합하다.

---

## Ⅱ. 구조 및 구성요소

```text
Head -> Node A(data,next) -> Node B(data,next) -> Node C(data,next) -> NULL
       / Singly: next 1개
       / Doubly: prev/next 2개
       / Tail: 마지막 노드 참조
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Head | 첫 노드 참조 | 빈 리스트는 NULL |
| Node | Data와 Next 저장 | 단일 노드는 포인터 1개 |
| Next | 다음 노드 주소 | 탐색 방향을 결정 |
| Tail | 마지막 노드 참조 | 큐 삽입 O(1)에 활용 |

> 요약: Head에서 시작해 Node의 Next를 따라가며 순서를 표현하고, Tail을 두면 끝 삽입 비용을 O(1)로 제한한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
위치 식별 -> 선행 노드 탐색 -> 포인터 변경 -> Head/Tail 보정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Head 또는 인덱스 기반 위치 식별 | 빈 리스트·첫 노드 여부 확인 |
| 2 | 선행 노드까지 순차 탐색 | 최악 O(n), curr != NULL |
| 3 | 삽입·삭제 포인터 변경 | next 손실 전 임시 참조 보관 |
| 4 | Head·Tail·size 보정 | size ±1, Tail NULL 참조 방지 |

> 요약: 연결 리스트 연산은 탐색 비용 O(n)과 포인터 변경 O(1)을 분리해 계산해야 한다.

---

## Ⅳ. 특징

| 구분 | 배열 | 연결 리스트 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 임의 접근 | 인덱스 O(1) | 순회 O(n) | 100만 번째 원소 접근 시 100만 회 이동 가능 |
| 중간 삽입 | 원소 이동 O(n) | 선행 노드 확보 후 O(1) | 포인터 2회 변경 |
| 메모리 배치 | 연속 공간 | 비연속 공간 | 노드당 포인터 1~2개 추가 |
| 캐시 지역성 | 연속 접근에 유리 | 포인터 추적으로 캐시 미스 증가 | CPU cache line 64B 기준 |

> 요약: 연결 리스트는 동적 수정 비용을 줄이지만, 임의 접근과 캐시 지역성은 배열보다 불리하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 배열 | 연결 리스트 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 연속 메모리, 인덱스 접근 | 비연속 노드, 포인터 연결 | 임의 접근 비중 70% 이상이면 배열 |
| 비용/성능 | 접근 O(1), 중간 수정 O(n) | 접근 O(n), 선행 노드 확보 후 수정 O(1) | 수정 위치 참조 보유 시 연결 리스트 |
| 운영/위험 | 재할당·복사 비용 | 포인터 오류·캐시 미스 | cache miss와 노드 수명 관리 필요 |

> 요약: 연결 리스트는 위치 참조가 있는 수정 작업에 유리하고, 조회 중심 워크로드는 배열이 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 포인터 손실 | 삭제 중 next 임시 보관 누락 | 삭제 순서 표준화, 단위 테스트 | null reference 발생 건수 |
| 탐색 지연 | Head부터 순회 | Tail·index·hash map 병행 | 평균 탐색 노드 수 |
| 캐시 미스 | 노드 비연속 배치 | memory pool, array-backed list 검토 | cache miss ratio |

> 요약: 연결 리스트 리스크는 포인터 무결성, 탐색 길이, 캐시 미스이며 테스트와 계측으로 확인한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 복잡도 | 참조 보유 삽입·삭제 O(1) | 마이크로벤치마크 |
| 무결성 | size, Head, Tail 불변식 100% 통과 | property-based test |
| 메모리 | 노드당 포인터 오버헤드 예산 내 | heap profiler |

> 요약: 성공 여부는 수정 비용, 포인터 불변식, 메모리 오버헤드를 함께 측정해 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 큐 구현: Head·Tail 포인터를 유지해 enqueue/dequeue를 O(1)로 처리하고 size 카운터 동기화
2. 해시 충돌 처리: Separate Chaining에서 버킷별 연결 리스트 사용, 평균 탐색 O(1+α) 관리
3. LRU 캐시: Doubly Linked List + Hash Map 조합으로 get/put을 O(1)에 처리

**결론 (2줄):**
- 기술사 판단: 임의 접근이 70% 이상이면 배열, 삽입·삭제가 빈번하고 위치 참조를 보유하면 연결 리스트가 적합함
- 향후 방향: 메모리 계층 영향으로 연결 리스트 단독보다 배열 기반 리스트, skip list, hash map 결합 설계가 필요함
