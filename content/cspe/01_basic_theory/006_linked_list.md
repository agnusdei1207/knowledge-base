# 연결 리스트 (Linked List)

## 1. 정의 및 개념

연결 리스트는 각 노드(Node)가 데이터와 다음 노드의 참조를 가지고, 포인터 연결을 통해 원소의 논리적 순서를 표현하는 선형 자료구조이다.

| 구분 | 정의 | 특징 |
|---|---|---|
| **노드(Node)** | 데이터와 링크를 포함한 저장 단위 | 데이터 + 포인터 |
| **단일 연결 리스트** | 각 노드가 다음 노드만 참조 | 구조 단순, 이전 노드 접근 어려움 |
| **이중 연결 리스트** | 각 노드가 이전·다음 노드를 모두 참조 | 양방향 순회, 삭제 용이 |
| **원형 연결 리스트** | 마지막 노드가 첫 노드를 참조 | 순환 처리, 라운드 로빈에 적합 |

연결 리스트는 배열처럼 연속 메모리를 요구하지 않으며, 노드 간 참조 변경으로 삽입·삭제를 처리한다.

## 2. 구조 및 주요 연산

```text
Head -> [Data|Next] -> [Data|Next] -> [Data|Next] -> null
```

**주요 연산**
- insert: 새 노드를 연결하여 삽입
- delete: 주변 노드의 링크를 변경하여 삭제
- search: Head부터 순차 탐색
- traversal: 각 노드를 순서대로 방문
- append/prepend: 꼬리 또는 머리에 노드 추가

삽입·삭제가 `O(1)`이라고 할 수 있는 것은 대상 위치 또는 이전 노드의 참조를 이미 알고 있을 때이다. 위치 탐색까지 포함하면 `O(n)`이 된다.

## 3. 배열과 연결 리스트 비교

| 구분 | 배열(Array) | 연결 리스트(Linked List) |
|---|---:|---:|
| 메모리 배치 | 연속 공간 | 비연속 가능 |
| 임의 접근 | `O(1)` | `O(n)` |
| 중간 삽입·삭제 | 원소 이동 필요, `O(n)` | 위치 참조 확보 시 `O(1)` |
| 캐시 지역성 | 좋음 | 낮을 수 있음 |
| 공간 오버헤드 | 낮음 | 포인터 저장공간 필요 |
| 크기 확장 | 재할당 가능 | 동적 확장 용이 |

검색과 순회가 많으면 배열이 유리하고, 위치를 알고 있는 삽입·삭제가 잦으면 연결 리스트가 유리하다.

## 4. 응용 분야

- 운영체제의 준비 큐, 대기 큐
- LRU(Least Recently Used) 캐시의 순서 관리
- 메모리 allocator의 free list
- 그래프 인접 리스트 표현
- 다항식, 희소 행렬의 동적 표현
- 브라우저 방문 기록, 음악 재생 목록
- 라운드 로빈 스케줄링의 원형 리스트

## 5. 심화 이슈 (기술사 포인트)

1. **임의 접근 한계**
   - 인덱스 기반 접근이 없어 특정 위치 검색은 Head부터 순차 탐색해야 한다.

2. **포인터 오버헤드**
   - 각 노드가 링크를 저장하므로 데이터 외 메모리 사용량이 증가한다.

3. **캐시 지역성 저하**
   - 노드가 메모리에 흩어지면 CPU 캐시 효율이 떨어진다.

4. **참조 갱신 오류**
   - 삽입·삭제 순서가 틀리면 연결 단절, 순환 오류, 메모리 누수가 발생한다.

5. **동시성 문제**
   - 순회 중 삽입·삭제가 발생하면 반복자 무효화와 Race Condition이 발생할 수 있다.

## 6. 결론

연결 리스트는 동적 크기 변화와 위치 기반 삽입·삭제에 강한 자료구조이다. 그러나 임의 접근, 캐시 효율, 포인터 오버헤드가 약점이므로 기술사 답안에서는 배열 대비 장단점과 `O(1)` 삽입·삭제의 전제 조건을 반드시 구분해야 한다.
