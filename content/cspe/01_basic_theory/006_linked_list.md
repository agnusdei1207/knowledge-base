## 미리 알고가기

- 노드: 데이터와 다음 노드 주소를 함께 가진 저장 단위임
- 포인터: 다음 노드의 메모리 위치를 가리키는 참조값임
- 단일·이중·원형 리스트: 포인터 방향과 끝 처리 방식에 따른 연결 리스트 유형임

## Ⅰ. 개요

- **정의**: 노드를 포인터로 연결한 동적 선형 자료구조임
- **배경/필요성**: 배열은 연속 메모리와 크기 변경 비용이 필요하므로, 잦은 삽입·삭제와 동적 크기 변경에는 포인터 기반 구조가 필요함
- **비유**: 각 객차가 다음 객차 연결고리를 들고 있는 열차 구조임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열 대비 연결 리스트의 구조·연산 특성 비교 | 노드, 포인터, 삽입·삭제 `O(1)`, 탐색 `O(n)`, 캐시 지역성 | 임의 접근 가능 단정, 포인터 비용 누락 |

> 요약: 연결 리스트는 삽입·삭제 유연성을 얻는 대신 순차 접근과 포인터 비용을 감수하는 자료구조임.

## Ⅱ. 특징/비교

| 판단 기준 | 배열 | 연결 리스트 |
|:---|:---|:---|
| 메모리 배치 | 연속 공간 | 비연속 노드 연결 |
| 임의 접근 | 인덱스로 `O(1)` | 처음부터 따라가며 `O(n)` |
| 삽입·삭제 | 중간 원소 이동으로 `O(n)` | 위치를 알고 있으면 포인터 변경 `O(1)` |

> 요약: 연결 리스트는 위치 접근보다 노드 연결 변경이 중요한 경우에 적합함.

- 단일 리스트는 메모리 사용이 적지만 이전 노드 접근이 어려움
- 이중 리스트는 양방향 이동과 삭제가 편하지만 포인터 저장공간과 갱신 비용이 증가함
- 원형 리스트는 라운드로빈 스케줄링처럼 끝에서 다시 처음으로 순환하는 구조에 적합함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Head     | ---> | Node     | ---> | Node     |
+----------+      +----------+      +----------+
                         |                 |
                         v                 v
                    +---------+       +---------+
                    | Data/Ptr|       | Data/Ptr|
                    +---------+       +---------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Head | 리스트의 첫 노드를 가리키는 시작 참조임 | 열차 맨 앞 위치 |
| Node | 데이터와 다음 노드 참조를 함께 저장하는 단위임 | 객차와 연결고리 |
| Pointer | 노드 사이의 연결 관계를 표현하는 주소 또는 참조임 | 다음 객차 고리 |
| Tail/NULL | 마지막 노드 또는 끝을 나타내는 참조 상태임 | 종착 표시 |

> 요약: 연결 리스트는 Head에서 시작해 노드의 포인터를 따라가며 선형 순서를 표현함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 위치탐색 | ---> | 노드생성 | ---> | 포인터수정 | ---> | 상태검증 |
+----------+      +----------+      +----------+      +----------+
```

1. **위치 탐색**: 삽입·삭제할 위치의 이전 노드 또는 대상 노드를 찾음
2. **노드 생성**: 삽입 시 데이터와 다음 참조를 가진 새 노드를 생성함
3. **포인터 수정**: 이전 노드, 새 노드, 다음 노드의 연결 관계를 갱신함
4. **상태 검증**: Head, Tail, NULL 처리와 리스트 순환 여부를 확인함

> 요약: 연결 리스트 연산은 위치를 찾은 뒤 포인터 연결을 끊고 다시 잇는 과정임.

## Ⅴ. 문제점

- **P1 캐시 지역성 저하**: 노드가 메모리에 흩어져 있어 순회 시 캐시 미스가 증가하고 배열보다 실제 지연이 커질 수 있음
- **P2 포인터 오류**: 삭제·삽입 중 참조 갱신 순서가 틀리면 끊어진 리스트, 순환, 메모리 누수가 발생함
- **P3 임의 접근 부적합**: k번째 원소 접근마다 Head부터 순회해야 하므로 검색·인덱스 기반 처리가 많은 업무에 불리함

> 요약: 연결 리스트는 포인터 유연성의 대가로 캐시 효율, 참조 안전성, 임의 접근 성능을 잃음.

## Ⅵ. 개선방안

1. **단기**: 포인터 갱신 순서, Head/Tail 예외, 빈 리스트 처리를 단위 테스트로 검증함
2. **중기**: 순회가 많은 업무는 배열·동적 배열·deque와 성능을 비교한 뒤 선택함
3. **장기**: 대규모 구조는 메모리 풀, intrusive list, safe pointer 정책으로 할당 비용과 참조 오류를 관리함

- **P1 대응**: 순차 접근 위주 업무는 배열 기반 구조로 대체 검토함 (확인: 캐시 미스, 순회 시간)
- **P2 대응**: 센티넬 노드와 소유권 규칙을 적용함 (확인: 누수 검사, 순환 검사)
- **P3 대응**: 임의 접근이 필요하면 인덱스 구조나 skip list를 검토함 (확인: k번째 접근 지연)

> 요약: 연결 리스트 개선은 포인터 안전성과 접근 패턴 검증을 먼저 수행해야 함.

## Ⅶ. 전망

- 현대 CPU에서는 메모리 접근 비용이 커져 단순 연결 리스트보다 캐시 친화적 배열 구조가 선호되는 경우가 많음
- 연결 리스트는 OS 커널, LRU 캐시, 그래프 인접 리스트처럼 삽입·삭제와 연결 변경이 중요한 영역에서 계속 쓰임
- 기술사는 연결 리스트를 배열의 대체재로 단정하지 말고 접근 패턴, 캐시 지역성, 메모리 안전성을 기준으로 선택해야 함
