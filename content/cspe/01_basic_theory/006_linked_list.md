# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 데이터와 다음 노드의 주소를 담은 **노드(Node)**를 **포인터(Link)**로 연결하여 만든 선형 자료구조.
- **물리적 특징**: 배열과 달리 메모리상에 연속적으로 존재하지 않고, 흩어져 있는 노드들을 논리적으로 연결함.
- **핵심 직관**: "각 칸이 다음 칸의 주소를 들고 있는 보물찾기 쪽지." (중간에 보물을 넣거나 빼려면 쪽지만 고쳐 쓰면 됨)

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **노드 (Node)** | 실제 데이터와 포인터를 담고 있는 기본 단위 | 기차의 한 칸 |
| **헤드 (Head)** | 리스트의 첫 번째 노드를 가리키는 포인터 | 기차의 기관차(시작점) |
| **단일 연결 리스트** | 한 방향(다음 노드)으로만 연결된 구조 | 일방통행 통로 |
| **이중 연결 리스트** | 앞뒤 양방향으로 연결되어 양방향 순회 가능 | 양방향 통로 (이전/다음 버튼) |
| **원형 연결 리스트** | 마지막 노드가 다시 첫 노드를 가리키는 구조 | 수건돌리기 (꼬리가 머리를 잡음) |

## 깊이 이해

- **배열(Array) vs 연결 리스트(Linked List)**:
  - **배열**: 인덱스로 즉시 접근($O(1)$) 가능하나, 중간 삽입/삭제 시 데이터를 밀고 당기는 오버헤드($O(N)$)가 큼.
  - **연결 리스트**: 중간 삽입/삭제 시 포인터만 바꾸면 되어 $O(1)$(위치를 알 때)이지만, 특정 위치를 찾으려면 처음부터 기어가야 함($O(N)$).

- **메모리 단편화와 지역성(Locality)**:
  - 연결 리스트는 노드가 메모리 여기저기 흩어져 있어 **캐시 지역성(Cache Locality)**이 매우 낮습니다. 
  - 현대 CPU는 연속된 메모리를 한꺼번에 가져오는(Prefetching) 기능이 강력하므로, 이론적인 $O(1)$ 삽입 성능에도 불구하고 순차 접근이 많은 경우 배열(혹은 `std::vector`)보다 현저히 느릴 수 있습니다.

- **데이터 삽입/삭제 메커니즘**:
  - **삽입**: `newNode->next = prevNode->next; prevNode->next = newNode;` (연결 순서 주의: 새 노드를 먼저 연결해야 기존 연결을 잃어버리지 않음)
  - **삭제**: `prevNode->next = targetNode->next; delete targetNode;`

- **고난도 응용: 스킵 리스트(Skip List)**:
  - 연결 리스트의 $O(N)$ 탐색 한계를 극복하기 위해, 여러 층의 링크(Index Layer)를 두어 **$O(\log N)$** 탐색을 구현한 구조. (Redis의 Sorted Set에서 활용)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 포인터를 이용한 **비연속적 메모리 할당**을 통해 데이터의 동적 삽입과 삭제에 최적화된 선형 자료구조임.
> 2. **가치**: 고정 크기 배열의 한계를 극복하고, 실행 시간(Runtime) 중에 **유연한 메모리 확장($O(1)$)**이 가능하게 함.
> 3. **판단 포인트**: 데이터의 **수정 빈도가 높으면 연결 리스트**, **조회 빈도가 높으면 배열**을 선택하는 것이 설계의 정석임.

## Ⅰ. 동적 메모리 관리의 핵심, 연결 리스트의 개요
### 1. 정의
- 데이터 원소들이 메모리 내에 흩어져 존재하며, 각 원소가 다음 원소의 주소를 저장함으로써 논리적 순서를 유지하는 방식.
### 2. 특징
- **동적 크기**: 컴파일 시점이 아닌 런타임에 필요한 만큼 노드를 추가/삭제 가능.
- **삽입/삭제 효율**: 데이터 이동(Shifting) 없이 포인터 조작만으로 처리.

## Ⅱ. 연결 리스트의 유형별 비교 및 메커니즘
### 1. 유형별 상세 비교
| 구분 | 단일 연결 리스트 | 이중 연결 리스트 | 원형 연결 리스트 |
|:---:|:---|:---|:---|
| **구조** | Data + Next Pointer | Prev + Data + Next | Last -> First 연결 |
| **순회** | 단방향 전진만 가능 | 양방향 자유 순회 | 무한 루프 순회 가능 |
| **메모리** | 포인터 1개 소요 | 포인터 2개 소요 (부담) | 단일/이중 구조에 적용 |
| **주 용도** | 단순 스택/큐 구현 | 복잡한 에디터, 브라우저 방문 기록 | 스케줄링(Round Robin) |

### 2. 시간 복잡도 분석
- **접근(Access) / 탐색(Search)**: $O(N)$ (Head부터 순차 탐색 필수).
- **삽입(Insertion) / 삭제(Deletion)**: $O(1)$ (단, 해당 위치의 포인터를 알고 있을 때 기준).

## Ⅲ. 배열(Array) vs 연결 리스트(Linked List) 심층 비교
| 항목 | 배열 (Array) | 연결 리스트 (Linked List) |
|:---:|:---|:---|
| **메모리 할당** | 정적 (컴파일 시점, Stack) | 동적 (실행 시점, Heap) |
| **메모리 배치** | **연속적 (Contiguous)** | **비연속적 (Non-contiguous)** |
| **접근 성능** | $O(1)$ (Random Access) | $O(N)$ (Sequential Access) |
| **삽입/삭제** | $O(N)$ (Data Shifting 발생) | $O(1)$ (Pointer 재연결) |
| **지역성** | 높음 (캐시 히트율 우수) | 낮음 (캐시 미스 잦음) |

## Ⅳ. 연결 리스트의 실무적 응용 사례
### 1. OS 및 시스템 소프트웨어
- **파일 시스템**: FAT(File Allocation Table) 방식에서 파일 블록 연결.
- **프로세스 스케줄링**: Ready Queue, Blocked Queue 관리.
### 2. 애플리케이션 레벨
- **Undo/Redo 기능**: 사용자의 액션 이력을 이중 연결 리스트로 관리.
- **LRU(Least Recently Used) 캐시**: 데이터의 사용 순서를 유지하기 위해 해시와 이중 연결 리스트 결합.

## Ⅴ. 기술사 관점의 성능 최적화 및 주의사항
### 1. 메모리 오버헤드
- 데이터 크기가 작을 경우(예: 4바이트 int), 포인터(8바이트)가 차지하는 비중이 더 커지는 배보다 배꼽이 큰 상황 발생.
- **대응**: 데이터 청크를 묶어서 관리하는 **언롤드 연결 리스트(Unrolled Linked List)** 고려.
### 2. 안정성 확보
- 포인터 조작 실수 시 메모리 누수(Memory Leak)나 댕글링 포인터(Dangling Pointer) 위험.
- **대응**: 스마트 포인터 사용 및 더미 노드(Dummy Node)를 활용한 예외 처리 간소화.

## Ⅵ. 기술사 관점의 결론: "메모리 유연성과 성능의 트레이드오프"
- 연결 리스트는 현대 프로그래밍에서 동적 자원 관리의 근간이나, **낮은 캐시 지역성**으로 인해 대규모 순차 처리에는 부적합할 수 있음.
- 아키텍트는 단순 알고리즘 복잡도($O$)에 매몰되지 않고, **CPU 캐시 계층 구조와 메모리 대역폭**을 고려하여 실제 런타임 성능을 극대화할 수 있는 자료구조를 선정해야 함.
