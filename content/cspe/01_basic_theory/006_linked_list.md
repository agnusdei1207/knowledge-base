# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 연결 리스트(Linked List)는 데이터를 담은 **노드**를 **포인터**로 이어 붙여 논리적 순서를 만드는 선형 자료구조로, 물리적으로 흩어진 노드를 링크로 연결한다.
- **왜 필요한가**: 배열은 연속된 메모리에 고정 크기로 잡혀 중간 삽입·삭제 시 뒤 원소를 모두 밀어야 O(N)이지만, 연결 리스트는 포인터만 바꿔 O(1)에 끼우고 뺄 수 있기 때문이다(O(1)·O(N) 성능 의미는 001·002 참조).
- **핵심 직관**: "각 칸이 다음 칸의 주소를 손에 쥐고 있다" — 보물찾기 쪽지처럼 노드마다 다음 위치가 적혀 있어, 중간에 하나 끼울 땐 앞뒤 쪽지만 고쳐 쓰면 된다.

## 핵심 용어 정리 (내부에 등장하는 것들)

배열과 달리 인덱스가 없고 포인터로 순서를 만드는 것이 핵심이다. 여기서 그 고유 용어를 세운다. 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 연결 리스트 (상위 키워드) | 노드를 포인터로 이어 만든 선형 구조 | 손 잡고 줄 선 사람들 |
| 노드 (Node) | 데이터와 다음 노드 주소를 담은 한 칸 | 물건 + "다음 사람 위치" 쪽지 |
| 포인터/링크 (Pointer) | 다음(또는 이전) 노드를 가리키는 주소 | 다음 칸을 가리키는 손가락 |
| 헤드 (Head) | 리스트의 첫 노드를 가리키는 시작점 | 줄의 맨 앞사람 |
| 테일 (Tail) | 마지막 노드(다음이 null인 끝) | 줄의 맨 뒷사람 |
| 단일/이중 연결 | 다음만 가리키기 / 이전·다음 모두 가리키기 | 앞만 보기 / 앞뒤 다 보기 |
| 원형 연결 (Circular) | 테일이 다시 헤드를 가리켜 고리를 이룸 | 손 잡고 원을 만든 사람들 |
| 순차 접근 (Sequential) | 헤드부터 링크를 따라가야 N번째에 도달 | 앞에서부터 손 잡고 세어 가기 |

## 깊이 이해
- **배경·문제의식**: 배열은 임의 접근(인덱스로 O(1))이 강점이지만, 크기가 고정이고 중간 삽입·삭제 때 뒤 원소를 전부 이동해야 해 O(N)이다. "원소 수가 자주 바뀌고 중간 삽입·삭제가 잦은" 상황을 위해, 연속 배치를 포기하고 포인터로 순서를 만든 것이 연결 리스트다.
- **작동 원리 (어떻게+왜)**:
  - 각 노드는 `[데이터 | 다음 주소]` 형태이고, 헤드에서 출발해 링크를 따라가며 순회한다.
  - 삽입: 새 노드의 next를 앞 노드의 다음으로 두고, 앞 노드의 next를 새 노드로 바꾼다 — **포인터 2개 수정**이라 위치를 알면 O(1)이다.
  - 삭제: 앞 노드의 next를 삭제 노드의 다음으로 건너뛰게 한다 — 역시 O(1)이다.
  - 반면 K번째 원소 접근은 헤드부터 K번 따라가야 하므로 O(N)이다 — 인덱스가 없기 때문이다.
- **비유**: 기차 객차 연결. 중간에 객차 하나를 넣을 땐 앞뒤 연결고리 2개만 풀었다 다시 채우면 된다(O(1)). 그러나 "7번째 객차"를 보려면 1번부터 세며 걸어가야 한다(O(N)).
- **구체 예시**: 100만 원소의 맨 앞 삽입은 배열이 100만 번 이동(O(N))이지만 연결 리스트는 포인터 1개 수정(O(1))이다. 반대로 50만 번째 원소 읽기는 배열이 O(1), 연결 리스트가 50만 번 순회(O(N))다.
- **흔한 오해·주의점**:
  - **삽입/삭제가 O(1)인 건 '위치를 이미 알 때'다.** 그 위치를 찾는 탐색 자체는 O(N)이라, "임의 값 삭제"는 탐색 O(N) + 삭제 O(1)이다.
  - **이진 탐색(004)을 못 쓴다.** mid로 한 번에 뛸 수 없어(임의 접근 불가) 정렬돼 있어도 O(log N)이 안 나온다.
  - 노드마다 포인터 저장 공간이 추가로 들고, 참조가 메모리 곳곳으로 튀어 캐시 지역성이 배열보다 낮다.

## 연결 개념
- **해시 테이블 (005)**: 체이닝 충돌 해결에서 각 버킷을 연결 리스트로 구현.
- **스택·큐 (007)**: 연결 리스트를 기반으로 한 삽입·삭제 특화 구조.
- **배열(Array)**: 임의 접근 O(1)·연속 메모리로 연결 리스트와 정반대 트레이드오프를 갖는 대비 구조.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 연결 리스트는 노드를 포인터로 이어 논리 순서를 만드는 선형 구조로, 중간 삽입·삭제를 O(1)에 처리함.
> 2. **가치**: 크기 가변·잦은 삽입 삭제 환경에서 배열의 O(N) 이동 비용을 제거해 동적 데이터 관리의 기반이 됨.
> 3. **판단 포인트**: 임의 접근이 O(N)이고 이진 탐색이 불가하므로, 접근 패턴이 순차·삽입 중심인지 임의 조회 중심인지가 배열과의 선택 기준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 포인터 기반 구조 이해 | 노드·포인터·헤드로 순서 형성 원리 | 배열과 구조 혼동, 연속 메모리로 오기 |
| 배열 대비 트레이드오프 | 삽입 O(1) vs 접근 O(N)의 방향 | 삽입 O(1)을 탐색 포함으로 오독 |
| 변형 구조 활용 판단 | 단일·이중·원형의 용도 차이 | 이진 탐색 적용 가능하다는 오류 |

> 요약: 포인터로 순서를 만드는 원리, 배열과의 삽입·접근 트레이드오프, 변형 구조별 용도를 함께 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 데이터와 다음 노드 주소를 담은 노드를 포인터로 이어 만든 선형 자료구조임
- 위치: (임의 접근 O(1)·고정 크기인 배열과 정반대로, 삽입·삭제 O(1)·가변 크기를 지향하는 구조임)
- 배경: 배열은 중간 삽입·삭제 시 뒤 원소를 모두 이동해 O(N) 비용이 발생함
- 필요성: 원소 수가 자주 바뀌고 중간 삽입·삭제가 잦은 동적 데이터 관리에 필수임

## Ⅱ. 구조 및 구성요소
선형 구조도 (노드 연결):

    Head -> [데이터|next] -> [데이터|next] -> [데이터|next] -> null(Tail)
            / 단일 연결 : next만 보유(앞으로만 순회)
            / 이중 연결 : prev·next 보유(양방향 순회)
            / 원형 연결 : Tail의 next가 Head를 가리켜 고리 형성

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드 | 데이터 + 다음(이전) 주소 저장 단위 | 포인터 저장으로 부가 공간 발생 |
| 포인터 | 노드 간 논리 순서 연결 | 링크 수정만으로 삽입·삭제 |
| 헤드 | 리스트 시작점 참조 | 유실 시 전체 접근 불가 |
| 테일 | 마지막 노드(next=null) | 원형은 헤드를 가리킴 |

> 요약: 노드가 포인터로 헤드부터 테일까지 이어지며, 연결 방식(단일·이중·원형)으로 순회 방향이 갈림.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (중간 삽입):

    삽입 위치 탐색(Head부터 순회) -> 새 노드 생성 -> 새노드.next = 앞노드.next -> 앞노드.next = 새노드

1. 위치 탐색: 헤드부터 링크를 따라 삽입·삭제 대상 지점까지 순차 이동함(O(N))
2. 삽입: 새 노드의 next를 앞 노드의 다음으로 연결한 뒤, 앞 노드의 next를 새 노드로 바꿈(O(1))
3. 삭제: 앞 노드의 next를 삭제 노드의 다음으로 건너뛰게 하여 링크에서 분리함(O(1))
4. 순회: 헤드에서 시작해 next가 null(또는 헤드 복귀)일 때까지 노드를 따라감

> 요약: 위치를 찾는 순회는 O(N)이나, 찾은 뒤 포인터 재연결로 삽입·삭제 자체는 O(1)에 완료함.

## Ⅳ. 특징
- 동적 크기: 노드를 그때그때 할당해 크기 제한 없이 확장·축소가 가능함
- 삽입·삭제 효율: 위치를 알면 포인터 수정만으로 O(1)에 삽입·삭제함
- 순차 접근 한계: 인덱스가 없어 K번째 접근·탐색이 O(N)이며 이진 탐색이 불가함
- 부가 비용: 노드마다 포인터 공간이 들고 참조 분산으로 캐시 지역성이 배열보다 낮음

## Ⅴ. 심화 비교 및 적용 판단

접근·삽입·메모리 축에서 배열과 대조함.

| 구분 | 연결 리스트 | 배열 (Array) |
|:---|:---|:---|
| 임의 접근(K번째) | O(N), 순차 순회 | O(1), 인덱스 직접 |
| 중간 삽입/삭제 | O(1), 포인터 수정(위치 인지 시) | O(N), 뒤 원소 이동 |
| 메모리 배치 | 비연속, 노드별 포인터 부가 | 연속, 부가 포인터 없음 |
| 탐색 알고리즘 | 순차 탐색만(이진 탐색 불가) | 정렬 시 이진 탐색 가능 |

> 요약: 임의 조회·이진 탐색이 필요하면 배열, 잦은 중간 삽입·삭제와 가변 크기가 필요하면 연결 리스트가 유리함.

**리스크·대응:**
- 헤드 참조 유실: 시작점 손실로 전체 접근 불가 → 헤드 참조 무결성 보장·더미 헤드 노드 사용
- 포인터 오류: 삽입·삭제 중 링크 끊김으로 노드 유실 → 연결 순서(새 노드 연결 후 기존 링크 교체) 준수
- 캐시 미스: 참조 분산으로 순회 지연 → 대량 순차 처리는 배열·연속 메모리 구조로 전환

**점검 지표:**
- 성능: 중간 삽입·삭제 처리량과 K번째 접근 지연 — 접근 패턴별 실측
- 무결성: 순회 중 순환 참조·널 포인터 발생률 — 링크 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 해시 충돌 처리: 해시 테이블(005) 체이닝에서 각 버킷을 연결 리스트로 구현해 동적 충돌 원소를 관리
2. LRU 캐시: 이중 연결 리스트 + 해시로 최근 사용 항목 이동·삭제를 O(1)에 처리해 캐시 교체를 구현
3. 큐·인접 리스트: 큐·그래프 인접 리스트를 연결 리스트 기반으로 구성해 가변 원소를 효율적으로 삽입·삭제

**결론:**
- 기술사 판단: 접근 패턴이 순차·삽입 중심이면 연결 리스트, 임의 조회·이진 탐색 중심이면 배열이 정답인 조건부 선택임
- 향후 방향: 캐시 지역성을 보완하기 위해 연속 메모리 블록에 노드를 배치하는 배열 기반 리스트·언롤드 리스트로 하이브리드화하는 추세임
