# 006. 연결 리스트 (Linked List)

## 미리 알고가기

- **노드 (Node)**: 데이터 필드와 다음 노드의 주소를 저장하는 포인터 필드로 구성된 기본 단위임
- **참조 지역성 (Locality of Reference)**: 데이터가 메모리에 인접해 있어 캐시 효율이 높아지는 성질이나, 연결 리스트는 분산 저장으로 인해 이 성질이 낮음
- **자기 참조 구조 (Self-referential Structure)**: 구조체 내부에서 자신의 타입을 가리키는 포인터를 포함하는 정의 방식임

## 1. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 함께 다음 노드를 가리키는 포인터를 포함하며, 물리적 메모리 위치와 상관없이 논리적 순서를 유지하는 선형 자료구조임
- **배경/필요성**: 정적 배열은 크기가 고정되어 있고 중간 삽입/삭제 시 대량의 데이터 이동($O(n)$)이 발생함. 실행 중 동적으로 크기를 변경하고, 포인터 조작만으로 $O(1)$의 삽입/삭제를 수행하여 메모리 활용도와 변경 유연성을 확보하기 위해 사용함

## 2. 특징 및 비교

연결 리스트는 메모리 할당의 유연성을 얻는 대신, 탐색 속도와 공간 효율성(포인터 오버헤드)을 희생함.

| 비교 항목 | 배열 (Array) | 연결 리스트 (Linked List) |
|:---|:---|:---|
| 메모리 할당 | 정적 할당 (컴파일 타임) | **동적 할당** (런타임) |
| 접근 방식 | 임의 접근 (Random Access, $O(1)$) | **순차 접근** (Sequential Access, $O(n)$) |
| 삽입/삭제 | 데이터 이동 필요 ($O(n)$) | **포인터 변경만 수행 ($O(1)$)** |
| 공간 효율 | 우수 (데이터만 저장) | 낮음 (포인터 저장 공간 추가 소요) |
| 캐시 효율 | 높음 (연속 저장) | 낮음 (불연속 저장으로 캐시 미스 발생) |

> 요약: 데이터 조회가 빈번하면 배열이 유리하고, 데이터의 삽입/삭제가 빈번하거나 데이터 총량을 예측하기 어려우면 연결 리스트가 유리함.

## 3. 구성요소/구조

연결 리스트는 연결 방식에 따라 단일, 이중, 원형 리스트로 분류되며 각기 다른 순회 특성을 가짐.

- **구성요소**:
  - **Head**: 리스트의 첫 번째 노드를 가리키는 포인터
  - **Tail**: 리스트의 마지막 노드를 가리키는 포인터 (끝점 추가 최적화)
  - **Data**: 실제 저장하고자 하는 정보
  - **Next Pointer**: 다음 노드의 메모리 주소
  - **Prev Pointer**: (이중 연결 시) 이전 노드의 메모리 주소

- **유형별 구조 (원리/흐름도)**:

```text
[단일 연결 리스트]
Head -> [D1|N] -> [D2|N] -> [D3|null]

[이중 연결 리스트]
Head <-> [P|D1|N] <-> [P|D2|N] <-> [P|D3|N] <-> Tail

[원형 연결 리스트]
Head -> [D1|N] -> [D2|N] -> [D3|N] --+
          ^                          |
          +--------------------------+
```

1. **단일 (Singly)**: 한 방향으로만 탐색 가능하며 구조가 단순함
2. **이중 (Doubly)**: 양방향 탐색 및 삭제가 용이하나 메모리를 더 사용함
3. **원형 (Circular)**: 마지막 노드가 처음으로 연결되어 순환 구조(라운드 로빈 등)에 적합함

## 4. 문제점 및 개선방안

1. **검색 속도 저하 ($O(n)$)**: 특정 데이터를 찾기 위해 반드시 Head부터 순차적으로 훑어야 하므로 대규모 데이터 검색에 부적합함
   - **개선방안**: 다층 인덱스를 추가하여 탐색 효율을 높인 **Skip List**를 사용하거나, 검색 빈도가 높은 데이터를 Head 쪽으로 옮기는 자가 구성 리스트(Self-organizing List)를 구현함 (확인: 평균 탐색 단계 수)

2. **메모리 단편화 및 캐시 미스**: 노드가 메모리 여기저기에 흩어져 있어 CPU 캐시 적중률이 낮고 잦은 동적 할당/해제로 인한 성능 저하가 발생함
   - **개선방안**: 노드들을 미리 큰 덩어리로 할당받아 사용하는 **메모리 풀 (Memory Pool)** 기법을 적용하거나, 인접한 메모리를 사용하는 정적 배열 기반의 연결 리스트를 설계함 (확인: 캐시 미스율 모니터링)

3. **포인터 관리 실수에 의한 장애**: 삽입/삭제 시 포인터 변경 순서가 틀리면 데이터 유실(Dangling Pointer)이나 무한 루프가 발생할 수 있음
   - **개선방안**: 리스트의 시작과 끝에 유효 데이터가 없는 **더미 노드 (Sentinel Node)**를 두어 삽입/삭제 시의 예외 조건을 제거하고 로직을 단순화함 (확인: 경계 조건 테스트)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 운영체제 (OS) 스케줄링 | 실행 대기 중인 프로세스들을 Ready Queue(연결 리스트)에 담아 순서대로 관리 | 컨텍스트 스위칭 오버헤드, 큐 삽입 지연 |
| 파일 시스템 (FAT) | 파일의 데이터 블록 위치를 연결 리스트 형태로 기록(File Allocation Table) | 파일 읽기 성능, 단편화 수준 |
| LRU 캐시 교체 알고리즘 | 최근에 사용된 데이터를 리스트 맨 앞으로, 오래된 것을 뒤로 보내며 교체 대상 식별 | 캐시 히트율, 데이터 이동 속도 |
| 그래프 인접 리스트 | 각 정점에 연결된 이웃 정점들을 연결 리스트로 매달아 메모리 효율적 표현 | 메모리 점유량, 특정 정점의 이웃 순회 시간 |

> 요약: 정해진 순서에 따라 데이터를 처리하거나, 메모리 효율보다 삽입/삭제의 유연성이 중요한 저수준 시스템 설계에 광범위하게 쓰임.

## 6. 결론

연결 리스트는 물리적 제약을 논리적 연결로 극복하는 유연한 자료구조의 전형임. 기술사는 단순히 포인터의 연결 관계를 넘어, 이 구조가 시스템의 캐시 성능과 메모리 관리에 미치는 영향을 깊이 이해해야 함.

특히 대규모 고성능 시스템에서는 연결 리스트의 탐색 한계를 극복하기 위해 Skip List나 Hash Table과의 결합 구조를 적극 검토해야 하며, 메모리 단편화 방지를 위한 커스텀 할당기 적용 등의 최적화 역량이 요구됨. 결국 연결 리스트는 그 자체로서의 가치보다 다른 복잡한 자료구조(트리, 그래프, 해시 충돌 처리 등)를 지탱하는 기초 빌딩 블록으로서의 의미가 큼.
