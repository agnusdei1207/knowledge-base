## 미리 알고가기

- 노드: 데이터를 저장하는 부분과 다음 노드를 잇는 연결 정보로 이루어진 기본 단위임
- 포인터 재연결: 원소를 옮기지 않고 연결 정보만 바꿔 삽입과 삭제를 처리하는 방식임
- 캐시 지역성: 메모리에 가까이 놓인 데이터를 연속해서 읽을수록 유리한 성질이며 연결 리스트는 이 점이 약함

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 각 노드가 자신의 데이터와 다음 노드의 연결 정보를 함께 가지며, 노드들이 메모리에 연속해서 놓이지 않아도 논리적 순서를 유지하는 선형 자료구조임
- **배경/필요성**: 배열은 중간 원소를 넣거나 빼면 뒤쪽 원소를 밀거나 당겨야 하므로, 구조 변경이 자주 일어나는 구간에서는 연결만 바꾸는 방식이 더 실용적임

## Ⅱ. 특징

- 삽입과 삭제 위치만 찾으면 원소를 이동하지 않고 연결 정보만 바꿔 구조를 수정할 수 있음
- 실행 중에 노드를 늘리거나 줄이기 쉬워 크기를 미리 고정하기 어려운 데이터 집합에 맞음
- 원하는 위치를 바로 찾을 수 없으므로 특정 노드까지는 앞에서부터 차례로 따라가야 함
- 노드가 메모리에 흩어져 배치되기 쉬워 반복 순회에서는 배열보다 캐시 효율이 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 배열 | 연결 리스트 |
|:---|:---|:---|
| 원하는 위치 접근 | 인덱스로 원하는 칸을 바로 찾을 수 있어 조회가 빠름 | 앞에서부터 링크를 따라가야 하므로 위치를 찾는 시간이 길어짐 |
| 중간 삽입과 삭제 | 뒤쪽 원소를 밀거나 당겨야 하므로 이동 비용이 큼 | 앞뒤 노드 연결만 바꾸면 되어 구조 수정이 단순함 |
| 메모리 배치 | 연속된 공간을 확보해야 하므로 크기 확장이 까다로움 | 비연속 공간에도 노드를 둘 수 있어 확장이 유연함 |
| 반복 순회 성능 | 인접한 원소를 연속해서 읽어 캐시 효율이 높음 | 노드가 흩어지기 쉬워 캐시 미스가 더 자주 발생함 |
| 적합한 업무 | 조회가 많고 위치 접근이 잦은 데이터 집합에 맞음 | 삽입과 삭제가 잦고 크기가 자주 바뀌는 데이터 집합에 맞음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 노드가 실제 값을 담는 영역이며, 검색하거나 갱신할 업무 데이터가 이곳에 저장됨 |
| 링크 필드 | 다음 노드를 가리키는 연결 정보이며, 이 값이 잘못 바뀌면 리스트 일부가 끊기거나 순환 구조가 생길 수 있음 |
| 헤드 포인터 | 첫 노드를 가리키는 시작점이며, 빈 리스트 판정과 첫 삽입 처리가 이 값을 기준으로 이루어짐 |
| 보조 포인터 | 삽입과 삭제 과정에서 현재 노드와 이전 노드를 함께 추적해 연결 순서를 안전하게 바꾸도록 돕는 참조값임 |

```text
+--------+     +----------------+     +----------------+     +------+
| Head   | --> | Node(data,next) | --> | Node(data,next) | --> | NULL |
+--------+     +----------------+     +----------------+     +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 위치탐색 | --> | 연결분리 | --> | 연결갱신 | --> | 무결성확인 |
+----------+     +----------+     +----------+     +----------+
```

1. **위치탐색**: 삽입하거나 삭제할 기준 노드까지 앞에서부터 차례로 이동함
2. **연결분리**: 삭제 대상이나 삽입 지점의 앞뒤 노드 관계를 잠시 끊어 변경할 위치를 분리함
3. **연결갱신**: 새 노드를 끼워 넣거나 대상 노드를 건너뛰도록 링크를 다시 연결함
4. **무결성확인**: 헤드 값, 마지막 노드 연결, 리스트 길이가 기대한 상태와 맞는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 운영체제 대기 목록처럼 중간 삽입과 삭제가 잦은 구조는 연결 리스트가 맞지만 포인터 갱신이 틀리면 구조가 깨지므로 삽입 지연시간과 구조 무결성 검사로 확인함
2. 자유 블록 목록처럼 크기가 계속 바뀌는 데이터는 연결 리스트로 다루기 쉽지만 조회가 많아지면 느려지므로 할당 실패율과 평균 탐색 단계 수를 함께 봄

## Ⅶ. 결론

연결 리스트는 원하는 위치를 곧바로 찾는 일보다 이미 찾은 위치에서 구조를 자주 바꾸는 일에 더 맞는 자료구조임.
