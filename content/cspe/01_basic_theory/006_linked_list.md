## Ⅰ. 개요
- **정의**: 노드가 데이터와 포인터를 가지며 포인터로 다음 노드를 연결하는 선형 자료구조
- **배경/필요성**: 배열은 연속 메모리를 요구하여 중간 삽입·삭제 시 전체 요소 이동이 필요하므로, 포인터 기반 동적 연결 구조가 요구됨
- **비유**: 보물찾기 쪽지 — 각 쪽지에 힌트(데이터)와 다음 쪽지 위치(포인터)가 적혀 있어 순서대로 따라가야 함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열 대비 구조적 차이 이해 | 삽입·삭제 O(1), 탐색 O(n) 시간복잡도 | 단일·이중·원형의 구조 차이를 혼동하지 않을 것 |

> 요약: 포인터로 노드를 연결하여 동적 크기 변경과 O(1) 삽입·삭제를 지원하는 선형 자료구조임

## Ⅱ. 구성요소
```text
  +------+------+     +------+------+     +------+------+
  | data | next-|---->| data | next-|---->| data | NULL |
  +------+------+     +------+------+     +------+------+
     Node 1              Node 2              Node 3
       ^
       |
     Head
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Node | 데이터 필드와 포인터 필드를 묶은 저장 단위 | 쪽지 한 장(내용 + 다음 위치) |
| Head | 리스트의 첫 번째 노드를 가리키는 시작 포인터 | 첫 번째 쪽지의 위치를 알려주는 지도 |
| `next` 포인터 | 현재 노드에서 다음 노드의 메모리 주소를 저장하는 필드 | 다음 쪽지가 숨겨진 장소 |
| `prev` 포인터 | 이중 연결 리스트에서 이전 노드 주소를 저장하는 필드 | 되돌아갈 수 있는 역방향 화살표 |
| Tail | 마지막 노드를 가리키는 포인터(원형에서는 Head로 연결) | 줄의 마지막 사람 |

> 요약: 노드(data + pointer)를 Head부터 순차 연결하며, 포인터 방향에 따라 단일·이중·원형으로 구분함

## Ⅲ. 절차
```text
  탐색 위치 결정     포인터 조정       노드 삽입/삭제     무결성 검증
  (대상 노드 탐색)  (전후 링크 변경)  (메모리 할당/해제)  (연결 상태 확인)
       |                |                  |                  |
       +---순회--------->+---링크 갱신----->+---반영---------->+
     Head부터 순회     prev/next 수정    새 노드 연결       순환/단절 점검
```
- 1단계: 삽입·삭제 대상 위치까지 Head에서 `next` 포인터를 따라 순회하여 탐색함
- 2단계: 대상 노드의 `prev`/`next` 포인터를 변경하여 연결 관계를 재설정함
- 3단계: 삽입 시 새 노드에 메모리를 할당하고 포인터를 연결하거나, 삭제 시 메모리를 해제함
- 4단계: 리스트 순회로 연결 무결성(순환 발생 여부, 단절 여부)을 검증함

> 요약: 순회 → 포인터 조정 → 노드 반영 → 무결성 검증의 4단계로 삽입·삭제를 수행함

## Ⅳ. 문제점
- 순차 탐색 비용: 인덱스가 없어 n번째 요소 접근 시 O(n) 순회 필요 — 임의 접근이 잦은 경우 지연 증가
- 메모리 오버헤드: 노드마다 포인터 필드(단일 1개, 이중 2개)를 추가 저장 — 소형 데이터에서 포인터가 데이터보다 큰 경우 발생
- 캐시 비친화성: 노드가 메모리에 비연속 배치되어 CPU 캐시 적중률 저하 — 대량 순회 시 배열 대비 처리 속도 감소

> 요약: 순차 탐색 O(n), 포인터 메모리 오버헤드, 캐시 미스 증가가 주요 한계임

## Ⅴ. 개선방안
1. 단기: 해시맵 인덱스를 병행하여 특정 키 기반 O(1) 접근 지원
2. 중기: 메모리 풀(Memory Pool) 기반 노드 할당으로 포인터 오버헤드와 할당 비용 절감
3. 장기: Unrolled Linked List(한 노드에 복수 요소 저장) 도입으로 캐시 적중률 개선

> 요약: 인덱스 병행 → 메모리 풀 → Unrolled 구조로 순차 탐색·오버헤드·캐시 문제를 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: Lock-Free Linked List 등 동시성 안전 구조로 멀티코어 환경 적용 확대
- 기술사적 판단: 배열과 연결 리스트의 장단점을 문제 특성에 따라 선택하는 설계 역량이 핵심임
- 기술사 제언: GC 기반 언어에서도 메모리 단편화와 캐시 효율을 고려한 자료구조 선택이 필요
