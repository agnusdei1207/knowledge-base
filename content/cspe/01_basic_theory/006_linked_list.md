## 핵심 답안

연결 리스트는 각 노드가 데이터와 다음 노드 참조를 갖고 포인터 연결로 원소의 순서를 표현하는 선형 자료구조이며, 위치를 알고 있는 노드의 삽입·삭제는 빠르지만 임의 접근과 캐시 효율은 배열보다 불리함.

```text
Head -> [Data|Next] -> [Data|Next] -> [Data|Next] -> null
```

기술사 답안에서는 연결 리스트를 배열보다 무조건 우수하다고 쓰지 말고, **삽입·삭제 위치를 이미 알고 있는가**, **탐색이 많은가**, **캐시 지역성과 포인터 오버헤드를 감당할 수 있는가**를 기준으로 선택해야 함.

## 배열과의 비교

| 판단 기준 | 배열 | 연결 리스트 |
|:---|:---|:---|
| 메모리 배치 | 연속 공간 | 노드가 흩어질 수 있음 |
| 임의 접근 | 인덱스로 `O(1)` | 앞에서부터 순차 접근 `O(n)` |
| 중간 삽입·삭제 | 원소 이동으로 `O(n)` | 위치 참조 확보 시 연결 변경 `O(1)` |
| 캐시 효율 | 높음 | 포인터 추적으로 낮을 수 있음 |
| 공간 오버헤드 | 데이터 중심 | 포인터 저장공간 추가 |
| 적합 상황 | 조회·순회 중심 | 위치 참조 기반의 잦은 삽입·삭제 |

연결 리스트의 `O(1)` 삽입·삭제는 "대상 위치 또는 이전 노드 참조를 이미 알고 있을 때" 성립하며, 위치를 찾는 비용은 별도임.

## 유형별 특징

| 유형 | 구조 | 장점 | 주의점 |
|:---|:---|:---|:---|
| 단일 연결 리스트 | 다음 노드만 참조 | 구조가 단순하고 포인터 오버헤드가 작음 | 이전 노드 접근이 어려움 |
| 이중 연결 리스트 | 이전·다음 노드 참조 | 양방향 순회와 삭제가 쉬움 | 포인터 저장과 갱신 비용 증가 |
| 원형 연결 리스트 | 마지막 노드가 처음 노드를 참조 | 순환 처리와 라운드 로빈에 적합 | 종료 조건 관리 필요 |
| 더미 노드 사용 | 실제 데이터 없는 경계 노드 추가 | 빈 리스트·첫 노드 삭제 처리 단순화 | 구조 설명이 필요함 |

LRU 캐시처럼 해시 테이블과 이중 연결 리스트를 결합하면 키 조회는 해시로, 순서 갱신은 리스트로 처리할 수 있음.

## 기본 연산 관점

1. **탐색**: 헤드에서 시작해 다음 참조를 따라가므로 일반적으로 `O(n)`임
2. **삽입**: 새 노드의 다음 참조를 먼저 연결한 뒤 이전 노드가 새 노드를 가리키게 함
3. **삭제**: 이전 노드가 삭제 대상의 다음 노드를 가리키도록 바꾸고 삭제 노드를 해제함
4. **순회**: null 또는 시작 노드 재도달 조건까지 모든 노드를 차례로 방문함
5. **경계 처리**: 빈 리스트, 첫 노드, 마지막 노드, 단일 노드 조건을 별도로 검증함

포인터 갱신 순서가 틀리면 기존 노드에 접근할 수 없거나 순환 오류가 생기므로, 삽입·삭제 답안에서는 참조 변경 순서를 간단히 제시하는 것이 좋음.

## 운영 리스크와 대응

| 리스크 | 원인 | 대응 |
|:---|:---|:---|
| 임의 접근 비용 | 인덱스 접근이 없어 순차 탐색 필요 | 조회 중심이면 배열·동적 배열·트리 검토 |
| 캐시 비효율 | 노드가 메모리에 흩어짐 | 메모리 풀, 배열 기반 리스트, 노드 압축 |
| 포인터 오류 | 삽입·삭제 순서 실수 | 더미 노드, 표준 템플릿, 단위 테스트 |
| 메모리 누수 | 삭제 노드 해제 누락 | 소유권 규칙, RAII, 누수 검사 |
| 동시성 문제 | 순회 중 삭제·삽입 | 잠금, 반복자 무효화 규칙, copy-on-write |

연결 리스트는 자료구조 개념상 단순하지만, 운영 코드에서는 포인터 안전성과 메모리 관리가 품질을 좌우함.

## 오해와 감점 포인트

- **삽입·삭제 항상 `O(1)` 오해**: 위치를 찾는 비용이 포함되면 `O(n)`이 될 수 있음
- **배열 대비 무조건 우수 표현**: 캐시 효율과 임의 접근에서는 배열이 유리함
- **단일·이중 구조 혼동**: 이전 노드 없이 단일 리스트의 중간 삭제를 `O(1)`로 쓰면 부정확함
- **메모리 오버헤드 누락**: 포인터 저장공간과 동적 할당 비용을 빼면 실무 판단이 약해짐
- **경계 조건 누락**: 빈 리스트, 헤드 삭제, 꼬리 삭제, 원형 종료 조건을 확인해야 함

## 답안 작성 포인트

1. 정의는 "노드와 참조로 순서를 표현하는 선형 자료구조"로 시작함
2. 배열과 비교해 임의 접근, 삽입·삭제, 메모리 배치, 캐시 효율을 설명함
3. 단일·이중·원형 리스트의 차이를 표로 제시함
4. 삽입·삭제는 참조 변경 순서를 언급함
5. 결론은 "삽입·삭제 위치를 알고 있는 동적 구조에는 유리하지만 검색 중심이면 배열·트리와 비교해야 한다"로 마무리함

> 기술사 관점에서 연결 리스트는 포인터 기반 동적 구조의 기본이지만, `O(1)` 삽입·삭제라는 장점은 위치 참조 확보와 안전한 참조 갱신을 전제로 함.
