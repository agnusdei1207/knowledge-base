## 미리 알고가기

- 노드(Node): 데이터와 링크를 함께 저장하는 기본 단위임
- 링크/포인터(Link/Pointer): 다음 또는 이전 노드 위치를 가리키는 참조임
- 순차 접근(Sequential Access): 헤드부터 링크를 따라 목표 위치까지 이동하는 방식임
- 불연속 할당: 노드가 메모리상에 연속 배치되지 않고 흩어져 저장되는 방식임

## Ⅰ. 개요

- **정의/개념**: 연결 리스트는 노드를 링크로 이어 물리적 연속성 없이 순서를 유지하는 동적 자료구조임
- **배경/필요성**: 배열은 크기 변경과 중간 갱신 시 이동 비용이 크므로 위치 기반 갱신에는 링크 조정 구조가 필요함

## Ⅱ. 특징

- 노드 단위로 할당하므로 연속 메모리 확보가 필요 없음
- 위치를 알고 있으면 링크 갱신만으로 삽입·삭제를 처리함
- 목표 위치 조회는 헤드부터 따라가므로 $O(n)$ 순차 탐색임
- 포인터 저장 공간과 캐시 지역성 저하를 함께 고려함

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 리스트 (Linked List) | 동적 배열 (Dynamic Array) |
|:---|:---|:---|
| **저장 방식** | 노드 단위 불연속 할당 | 연속 메모리 블록 할당 |
| **조회** | $O(n)$, 링크 순차 탐색 | $O(1)$, 인덱스 직접 접근 |
| **삽입·삭제** | 위치 파악 후 $O(1)$ | 중간 갱신 시 $O(n)$ 이동 |
| **캐시 지역성** | 낮음, 포인터 추적으로 분산 접근 | 높음, 연속 데이터 접근 |
| **주요 비용** | 포인터 공간, 탐색 지연 | 확장 시 재할당·복사 |

> 요약: 위치가 알려진 갱신은 연결 리스트가 유리하고, 조회 중심 구조는 동적 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 필드 | 저장 대상 값이나 객체 참조를 담는 영역임 |
| 링크/포인터 | 다음 또는 이전 노드를 가리켜 논리적 순서를 만듦 |
| 헤드($Head$) | 첫 노드를 가리키는 탐색 진입점임 |
| 테일($Tail$) | 끝 삽입을 빠르게 하는 선택 포인터임 |

```text
[ 단방향 연결 리스트 구조 ]
+------+      +---------------+      +---------------+      +------+
| Head | ---> | Data | Next --| ---> | Data | Next --| ---> | NULL |
+------+      +---------------+      +---------------+      +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 위치 탐색    | --> | 링크 교체    | --> | 참조 정리    | --> | 경계 확인    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **위치 탐색**: $Head$부터 갱신 지점의 이전 노드까지 이동함
2. **링크 교체**: 삽입·삭제 대상의 앞뒤 링크를 바꿈
3. **참조 정리**: 삭제 노드 참조를 해제해 누수를 막음
4. **경계 확인**: $Head$, $Tail$, $NULL$ 값이 올바른지 확인함

## Ⅵ. 실무 적용 및 유의점

1. LRU 캐시·프리 리스트는 대상 포인터 보유 시 연결 리스트로 갱신하고 누락 테스트로 확인함
2. 조회 중심 컬렉션은 배열·트리를 우선 검토하고 순차 탐색 비용을 측정함

## Ⅶ. 결론

- 연결 리스트는 위치가 명확한 삽입·삭제에 쓰고, 조회 비용과 포인터 안전성을 함께 검증함
