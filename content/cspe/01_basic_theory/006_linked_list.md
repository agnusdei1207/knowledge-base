# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 데이터 덩어리(노드)들이 물리적으로 흩어져 있되, 각 노드가 '다음 노드의 주소'를 가리키는 포인터로 논리적 순서를 유지하는 선형 자료구조다.
- **왜 필요한가**: 크기가 고정된 배열(Array)의 한계를 극복하고, 실행 중에 크기를 자유롭게 늘리거나 줄이기 위해 고안되었다.
- **핵심 직관**: 보물찾기 쪽지. 1번 쪽지에 "다음 보물은 나무 밑에 있음"이라고 적혀 있고, 나무 밑에 가면 "다음 보물은 돌 밑에 있음"이라 적힌 식이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 노드 (Node) | 연결 리스트를 구성하는 기본 단위 (데이터 + 포인터) | 보물찾기 쪽지 한 장 |
| 포인터/링크 (Pointer/Link) | 다음 노드가 메모리상 어디에 있는지 알려주는 주소값 | 쪽지에 적힌 '다음 목적지 약도' |
| 헤드 (Head) | 연결 리스트의 맨 첫 번째 노드 주소 | 보물찾기 첫 번째 단서의 위치 |
| 단일 연결 리스트 (Singly Linked List) | 한쪽 방향(다음 노드)으로만 연결된 구조 | 일방통행 골목길 |

## 깊이 이해
- **배경·문제의식**: 배열(Array)은 메모리상에 '연속된 빈 공간'을 미리 잡아둬야 한다. 중간에 데이터를 끼워 넣으려면 뒤의 데이터를 전부 한 칸씩 밀어야(O(N)) 해서 비효율적이며, 처음에 크기를 잘못 잡으면 메모리가 낭비되거나 부족해진다.
- **작동 원리**: 
  - 각 노드는 실제 메모리 어디에 있든 상관없다. 
  - 새 데이터를 중간에 넣고 싶으면: 이전 노드의 포인터를 새 노드로 향하게 하고, 새 노드의 포인터를 다음 노드로 향하게 끈만 고쳐 묶으면 된다 (O(1)).
- **비유**: 
  - 배열: 영화관에서 10자리를 연달아 예매한 10명. 중간에 친구가 오면 다 같이 일어나서 한 칸씩 이동해야 한다.
  - 연결 리스트: 놀이공원에서 흩어져 노는 10명. 각자 "내 다음 사람은 롤러코스터에 있다"고 핸드폰 번호만 알고 있으면 된다. 중간에 친구가 오면 연락처 순서만 업데이트하면 끝이다.
- **구체 예시**: 웹 브라우저의 '뒤로가기/앞으로가기' 기능은 앞뒤로 이동이 자유로운 이중 연결 리스트(Doubly Linked List)로 구현된다.
- **흔한 오해·주의점**: 연결 리스트의 '삽입/삭제 시간 복잡도는 O(1)이다'라는 말은 반만 맞다. 포인터를 바꾸는 작업 자체는 O(1)이지만, **삽입할 위치(중간 노드)까지 찾아가는 탐색 시간은 첫 노드부터 순차 탐색해야 하므로 O(N)이 걸린다.** 즉, 배열처럼 5번째 데이터를 단번에 조회하는 랜덤 액세스(O(1))는 절대 불가능하다.

## 연결 개념
- 배열 (Array): 연결 리스트와 항상 비교되는 라이벌 (읽기는 배열, 쓰기는 연결 리스트).
- 스택/큐 (007 참조): 연결 리스트를 활용해 구현하기 좋은 대표적 논리 구조.
- 해시 체이닝 (005 참조): 해시 충돌 시 무한 확장을 위해 연결 리스트를 사용.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 연결 리스트는 메모리의 비연속적 공간에 노드(데이터+주소)를 동적으로 할당하고 포인터로 논리적 순서를 잇는 자료구조다.
> 2. **가치**: 크기 가변성이 보장되며, 배열에서 O(N)의 오버헤드가 발생하는 데이터 중간 삽입/삭제를 포인터 스위칭만으로 신속히 처리할 수 있다.
> 3. **판단 포인트**: '삽입/삭제의 유연성'이라는 이면에는 '순차 탐색에 따른 조회 속도 저하(O(N))'와 '포인터용 추가 메모리 오버헤드'라는 트레이드오프가 존재하므로, 읽기/쓰기 빈도에 따라 배열과 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열(Array)과 연결 리스트의 트레이드오프 비교 | 연속 메모리(랜덤 액세스) vs 비연속 동적 메모리(순차 탐색) 성능 비교표 | 삽입/삭제가 무조건 빠르다고 단정함 (탐색 O(N) 간과) |
| 연결 리스트의 종류 및 특성 숙지 | 단일, 이중(Doubly), 원형(Circular) 구조 차이 | 기본 단일 구조만 서술하고 변형 구조 누락 |
| 자료구조 선택의 아키텍처 관점 판단 | 캐시 지역성(Cache Locality) 저하 문제, 오버헤드 | 학술적 포인터 구조 설명에만 지면 낭비 |

> 요약: 연결 리스트는 동적 삽입/삭제의 강점과 탐색(O(N))/캐시 효율 저하의 약점을 배열과 비교하여 트레이드오프 관점에서 서술해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 연결 리스트는 각 노드가 데이터와 포인터를 가지며, 포인터 연결을 통해 논리적 순서를 유지하는 동적 크기 할당 자료구조임
- 배경: 정적 배열(Array)은 연속된 물리 메모리를 선점해야 하고 데이터의 중간 삽입/삭제 시 O(N)의 데이터 시프트(Shift) 오버헤드가 발생함
- 필요성: 런타임에 데이터 크기가 가변적으로 변하며 빈번한 데이터 추가/제거가 일어나는 큐, 스택, 덱 시스템 구현의 근간 구조로 필요함

---

## Ⅱ. 구조 및 구성요소

```text
[Head 포인터] -> [Node 1] -> [Node 2] -> [Node 3] -> Null
               (Data|Next)   (Data|Next)   (Data|Next)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드 (Node) | 실질적인 데이터를 담는 단위 컨테이너 | 값(Data) 영역과 주소(Pointer) 영역으로 구성 |
| 링크 (포인터) | 메모리상에 흩어진 다음 노드의 위치 주소값 저장 | 단방향(단일), 양방향(이중) 등 구조 결정 |
| Head / Tail | 리스트의 시작점(Head)과 끝점(Tail)을 가리키는 외부 참조 | Head 유실 시 전체 연결 리스트 데이터 고아(Orphan)화 |

> 요약: 노드와 포인터 기반의 느슨한 물리적 연결을 통해, 크기가 고정되지 않은 유연한 논리적 선형 구조를 완성한다.

---

## Ⅲ. 동작원리 및 흐름도 (데이터 삽입 기준)

```text
삽입 요청 -> 노드 동적 할당 -> 삽입 위치 탐색 (순차 접근)
  |
  +-> 새 노드 Next = 이전 노드의 Next 연결
  +-> 이전 노드 Next = 새 노드로 주소 변경 -> 삽입 완료
```

- 1단계 [메모리 할당]: 힙(Heap) 영역에 새로운 노드 1개 크기만큼의 동적 메모리를 할당하고 데이터 입력
- 2단계 [위치 탐색]: Head부터 링크를 따라가며 O(N)의 시간 복잡도로 삽입/삭제할 타겟 위치 탐색
- 3단계 [포인터 스위칭]: 인접 노드의 링크 주소만 새 노드로 변경하여 논리적 삽입 수행 (데이터 시프트 없음)
- 4단계 [가비지 컬렉션]: 삭제의 경우, 끊어진 기존 노드 메모리를 해제하여 누수(Leak) 방지

> 요약: 데이터 시프트 없이 단 두 번의 포인터 주소 변경(O(1))만으로 물리적 이동 없이 논리적 삽입/삭제를 완료한다.

---

## Ⅳ. 특징

- 동적 메모리 활용: 크기 제한 없이 필요한 순간에만 메모리를 할당받아 사용하므로 메모리 파편화(Fragmentation) 공간 낭비 방지
- 순차 접근 한계: 인덱스 기반 랜덤 액세스(O(1))가 불가능하여, 특정 N번째 요소 탐색 시 무조건 O(N) 지연 발생
- 오버헤드: 실제 데이터 외에 포인터(주소 4/8바이트) 저장을 위한 추가적인 메모리 오버헤드 상시 수반

> 요약: 런타임 메모리 유연성과 쓰기(Write) 성능은 극대화되나, 읽기(Read) 성능과 공간 효율성 측면에서는 배열 대비 열세다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 배열 (Array) | 연결 리스트 (Linked List) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 / 메모리 | 연속 할당 (정적 크기) | 비연속 동적 할당 (포인터 추가) | 데이터 크기의 가변성 여부 |
| 탐색 (Read) | O(1) (인덱스 랜덤 액세스) | O(N) (순차 탐색 필수) | 검색/조회 연산의 빈도 |
| 삽입·삭제 (Write)| O(N) (데이터 시프트 발생) | O(1) (위치 탐색 시간 별도) | 데이터 변경(삽입/삭제) 빈도 |
| 하드웨어 특성 | 캐시 지역성(Locality) 극대화 | 메모리 산포로 인한 캐시 미스 잦음 | 고성능 CPU 캐시 활용 필요성 |

> 요약: 읽기(조회)가 많은 정적 데이터는 배열을, 쓰기(삽입/삭제)가 많은 동적 데이터는 연결 리스트를 시스템 골격으로 채택한다.

**리스크·대응 (기본은 불릿):**
- 단일 실패점 리스크: 특정 노드의 포인터 유실이나 단절 시 이후 모든 데이터 구조가 미아 상태(Memory Leak)에 빠짐 -> 양방향 접근 가능한 이중 연결 리스트(Doubly Linked List)로 내결함성 보완 (지표: 노드 순회 에러율)
- 캐시 미스(Cache Miss) 성능 저하: 노드가 메모리 전역에 흩어져 있어 CPU 캐시 히트율 급락 -> 대규모 순차 처리가 필수인 경우 연속 메모리 풀(Pool)을 선할당하여 사용하거나 배열로 설계 변경 (지표: L1/L2 Cache Miss Ratio)

**도입 후 점검 지표 (기본은 불릿):**
- 성능/효율: 데이터 10만 건 중간 삽입 시 소요 시간(ms) — APM 기반 배열 vs 리스트 Write 벤치마크 지표
- 품질/운영: 사용 중인 노드의 총 크기 대비 실제 포인터 오버헤드 메모리 점유율 — 힙 메모리 덤프 분석

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. OS 스케줄링 큐: 잦은 컨텍스트 스위칭과 프로세스 생성/종료가 일어나는 OS의 Ready/Wait 큐를 연결 리스트(원형 큐)로 구현하여 시프트 오버헤드 제거
2. 해시 충돌 방어(Chaining): 해시 테이블에서 동일 버킷으로 매핑되는 충돌 데이터를 무한 확장이 가능한 연결 리스트 체이닝으로 엮어 데이터 유실 방어
3. LRU(Least Recently Used) 캐시 구현: Hash(조회 O(1))와 이중 연결 리스트(갱신 O(1))를 결합하여 최신 참조 데이터를 빠르게 교체하는 고성능 LRU 알고리즘 설계

**결론 (2줄):**
- 기술사 판단: 실무 시스템에서 단일 연결 리스트 원형 그대로 쓰이는 경우는 드물며, Tree, Graph, Queue 등 복합 자료구조를 지탱하는 내부 동적 메모리 제어 메커니즘으로 활용하는 것이 타당함
- 향후 방향: 최근 H/W는 CPU 캐시 성능이 극도로 발전하여, 연결 리스트의 캐시 미스 비용이 배열의 삽입 O(N) 비용보다 커지는 구간이 생기므로 실측 기반의 자료구조 선택이 요구됨
