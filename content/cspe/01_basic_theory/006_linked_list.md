## Ⅰ. 개요
- **정의**: 데이터와 포인터로 구성된 노드를 비연속 메모리에 연결하여 선형 저장하는 자료구조
- **배경/필요성**: 배열은 삽입·삭제 시 O(N) 이동이 필요하므로, 포인터 변경만으로 O(1) 삽입·삭제가 가능한 동적 구조가 필요함
- **비유**: 종이접기 기차처럼, 각 칸(노드)이 다음 칸의 고리(포인터)를 잡고 이어진 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열과의 트레이드오프 이해 | 삽입·삭제 O(1) vs 탐색 O(N) 비교 | 삽입 O(1)은 위치를 아는 경우에 한정됨을 명시 |
| 단일/이중/원형 구조 차이 파악 | 각 변형의 포인터 구성과 용도 | 이중 연결의 메모리 오버헤드 언급 필요 |

> 요약: 포인터 기반 비연속 메모리 연결로 동적 삽입·삭제에 유리하나 임의 접근이 불가한 선형 자료구조임

## Ⅱ. 구성요소
```text
  [Singly Linked List]
  Head --> |Data|Next| --> |Data|Next| --> |Data|NULL|

  [Doubly Linked List]
  NULL <--|Prev|Data|Next| <--> |Prev|Data|Next| <--> |Prev|Data|Next|--> NULL

  [Circular Linked List]
  Head --> |Data|Next| --> |Data|Next| --> |Data|Next| --+
    ^                                                     |
    +-----------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 노드 | 데이터 필드와 포인터 필드를 포함하는 저장 단위 | 기차 한 칸(짐칸 + 연결 고리) |
| 포인터(Next) | 다음 노드의 메모리 주소를 저장하는 참조 | 다음 칸을 가리키는 고리 |
| 포인터(Prev) | 이중 연결에서 이전 노드 주소를 저장하는 참조 | 앞 칸으로 돌아가는 고리 |
| Head | 리스트 첫 번째 노드를 가리키는 진입점 포인터 | 기차 맨 앞 기관차 |
| Tail | 리스트 마지막 노드를 가리키는 포인터(선택적) | 기차 꼬리 표시등 |

> 요약: 노드(데이터+포인터), Head/Tail 포인터가 연결 리스트의 핵심 구성요소임

## Ⅲ. 절차
```text
  삽입 요청(위치 p, 데이터 d)
      |
      v
  새 노드 N 생성(data=d)
      |
      v
  N.next = p.next (새 노드가 후속 노드를 가리킴)
      |
      v
  p.next = N (선행 노드가 새 노드를 가리킴)
```
- 1단계: 삽입 위치의 선행 노드 `p`를 탐색하여 확보 (탐색 자체는 O(N))
- 2단계: 새 노드 `N`을 동적 메모리에 할당하고 데이터 저장
- 3단계: `N.next`를 `p.next`로 설정하여 후속 노드와 연결
- 4단계: `p.next`를 `N`으로 갱신하여 선행 노드와 연결 완료 (포인터 변경 O(1))

> 요약: 선행 노드 탐색 → 노드 생성 → 후속 연결 → 선행 연결 순서로 삽입이 수행됨

## Ⅳ. 문제점
- 순차 탐색 강제: 인덱스 기반 임의 접근이 불가하여 N번째 원소 탐색에 O(N) 순회가 필요함
- 포인터 메모리 오버헤드: 노드마다 포인터 필드(단일 8바이트, 이중 16바이트)가 추가되어 소형 데이터 저장 시 데이터 대비 오버헤드 비율이 높아짐
- 캐시 비친화성: 노드가 힙에 비연속 배치되어 CPU 캐시 라인 적중률이 배열 대비 저하됨

> 요약: 순차 탐색 강제, 포인터 오버헤드, 캐시 비친화성이 연결 리스트의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 스킵 리스트 적용으로 다단계 인덱스를 두어 탐색을 O(log N)으로 개선
2. 중기: 언롤드 연결 리스트(unrolled linked list) 도입으로 노드당 복수 원소를 저장하여 포인터 비율 감소
3. 장기: 메모리 풀 할당기 사용으로 노드를 연속 메모리 블록에 배치하여 캐시 적중률 향상

> 요약: 스킵 리스트, 언롤드 구조, 메모리 풀로 탐색·오버헤드·캐시 문제를 각각 대응함

## Ⅵ. 전망
- 발전 방향: Lock-free 연결 리스트가 멀티스레드 환경의 동시성 자료구조로 활용 범위가 확대 중임
- 기술사적 판단: 해시 테이블 체이닝(005 참조), 스택·큐(007 참조), 트리(008 참조) 등 상위 자료구조의 내부 구현 기반으로서 중요성이 유지됨
- 기술사 제언: 삽입·삭제 빈도와 탐색 빈도의 비율을 분석하여 배열과 연결 리스트 중 적합한 구조를 선택할 필요가 있음
