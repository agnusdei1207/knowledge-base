# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 연결 리스트는 데이터와 다음 노드의 메모리 주소(포인터)를 함께 저장하는 노드(Node)들이 사슬처럼 이어진 **포인터 기반 동적 선형 자료구조**다. 배열과 함께 가장 기본적인 두 **선형 자료구조** 중 하나다.
- **왜 필요한가**: 배열은 생성 시점에 연속된 메모리 블록을 통째로 확보해야 하고, 중간에 원소를 넣거나 빼려면 뒤 원소를 전부 밀어야(Shift) 한다. 연결 리스트는 흩어진 메모리 조각을 포인터로 이어붙여, 크기를 실행 중에 자유롭게 늘리고 삽입·삭제를 포인터 조작만으로 끝낸다.
- **핵심 직관**: 보물찾기 쪽지 릴레이다. 첫 쪽지(Head)를 열어야 다음 쪽지 위치를 알 수 있고, 그 쪽지를 열어야 또 다음 위치를 안다 — 순서대로 하나씩만 따라갈 수 있다.

## 핵심 용어 정리
| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 선형 자료구조 | 원소가 하나의 순서열로 나열되는 자료구조(배열·리스트·스택·큐의 상위 범주) | 한 줄로 선 사람들 |
| 동적 자료구조 | 크기가 고정되지 않고 실행 중에 늘고 주는 자료구조 | 신축 가능한 옷 |
| 노드(Node) | 데이터 필드 + 포인터 필드로 구성된 하나의 저장 단위 | 보물찾기 쪽지 한 장 |
| 데이터 필드 | 노드가 실제로 담는 값 | 쪽지에 적힌 보물 정보 |
| 포인터(링크) 필드 | 다음(또는 이전) 노드의 메모리 주소를 담는 필드 | 쪽지에 적힌 "다음 위치" |
| 헤드(Head) | 리스트 순회의 유일한 진입점, 첫 노드를 가리키는 포인터 | 첫 번째 쪽지가 있는 곳 |
| 테일(Tail) | 마지막 노드(또는 그것을 가리키는 포인터) | 마지막 쪽지 |
| 단일 연결 리스트 | 각 노드가 다음 노드만 가리킴 | 한쪽 방향 화살표 사슬 |
| 이중 연결 리스트 | 각 노드가 이전·다음 노드를 모두 가리킴 | 양방향 화살표 사슬 |
| 환형 연결 리스트 | 마지막 노드가 다시 첫 노드를 가리켜 원형을 이룸 | 꼬리를 문 뱀 |
| 동적 할당 | 실행 중 운영체제에 메모리를 요청해 확보하는 것 | 필요할 때마다 방 하나씩 빌리기 |

## 깊이 이해

### 배열과 근본적으로 다른 점 — 물리적 연속성 vs 논리적 연속성
배열은 원소들이 메모리 주소상으로 실제로 붙어 있어야 한다(물리적 연속). 그래서 인덱스 i의 주소를 `시작주소 + i*원소크기`라는 계산 한 번(O(1))으로 구할 수 있다. 연결 리스트는 이 제약을 버린다. 노드는 메모리 어디에 흩어져 있어도 되고, 대신 각 노드가 "다음 노드의 주소"를 들고 있어서 논리적인 순서만 유지한다(논리적 연속성). 이 차이 하나가 배열과 연결 리스트의 성능 차이 대부분의 근원이다.

### 삽입·삭제가 왜 빠른가 — 수치로 확인
1,000개짜리 배열의 맨 앞에 원소를 하나 삽입한다고 하자. 기존 1,000개를 전부 한 칸씩 뒤로 밀어야 하므로 999번의 이동 연산이 필요하다(O(N)). 반면 연결 리스트는 새 노드를 만들고, 새 노드의 포인터가 기존 헤드를 가리키게 한 뒤 헤드 포인터를 새 노드로 바꾸는 것으로 끝난다 — 노드 개수와 무관하게 항상 포인터 두 번 갱신, O(1)이다.

단, 이것은 "삽입할 위치를 이미 알고 있을 때"에만 해당한다. 만약 "700번째 위치에 넣어라"처럼 위치를 찾아야 한다면, 헤드부터 699번 포인터를 따라가야 하므로 탐색에 O(N)이 걸린다. 그래서 연결 리스트의 진짜 이점은 "이미 손에 쥐고 있는 노드 앞뒤에 삽입·삭제"할 때 극대화된다 — 예를 들어 순회 중인 반복자(iterator)가 가리키는 위치에 삽입하는 경우다.

### 탐색이 왜 느린가 — O(N)의 대가
배열은 인덱스로 임의 위치에 즉시 접근(Random Access)하지만, 연결 리스트는 반드시 헤드부터 포인터를 하나씩 따라가야 한다. 10,000개 노드 중 9,999번째 노드를 읽으려면 포인터를 9,999번 따라가야 한다 — 배열이라면 주소 계산 한 번으로 끝나는 일이다. 이 탐색 비용(O(N))이 연결 리스트가 "조회 중심" 워크로드에 불리한 이유다.

### 단일·이중·환형의 차이와 쓰임
단일 연결 리스트는 다음 노드만 알기 때문에 역방향 이동이 불가능하다 — 예를 들어 어떤 노드를 삭제하려면 "그 노드의 이전 노드"를 알아야 포인터를 재배치할 수 있는데, 단일 연결 리스트는 이전 노드를 모르므로 다시 헤드부터 탐색해야 한다. 이중 연결 리스트는 각 노드가 prev·next 포인터를 모두 가져 양방향 이동이 가능하고, 임의 노드 삭제 시 이전 노드를 즉시 알 수 있어 O(1)에 포인터 재배치가 끝난다. 대신 노드마다 포인터를 하나 더 저장해야 하는 메모리 오버헤드가 있다. 환형 연결 리스트는 테일이 다시 헤드를 가리켜, "끝에서 다시 처음으로" 순환하는 구조(예: 라운드 로빈 스케줄링)에 적합하다.

### 메모리 오버헤드 — 수치로 확인
64비트 시스템에서 정수(4바이트) 하나를 저장한다고 하면, 배열은 그 4바이트(+정렬 패딩)만 쓰면 되지만, 단일 연결 리스트는 데이터 4바이트에 포인터 8바이트가 추가로 붙어 노드 하나에 최소 12바이트(패딩 포함 시 16바이트) 필요하다. 즉 데이터 자체보다 포인터가 더 큰 메모리를 차지할 수 있다 — 이중 연결 리스트는 포인터가 두 개이므로 오버헤드가 더 커진다(약 20~24바이트). 데이터가 작을수록 이 오버헤드 비율은 커진다.

### 흔한 오해
"연결 리스트는 삽입·삭제가 배열보다 항상 빠르다"는 오해가 가장 흔하다. 실제로는 삽입 "위치를 찾는" 비용이 O(N)으로 남아 있어, 위치를 모르는 상태에서의 삽입은 배열의 O(N)과 다를 바 없다. 진짜 이점은 위치를 이미 아는 상태에서의 O(1) 포인터 재배치와, 크기가 고정되지 않는다는 점이다.

## 연결 개념
- 007 스택·큐·덱 — 연결 리스트를 내부 구현체로 사용하는 대표 자료구조
- 배열(Array) — 연속 메모리 기반의 대조 구조, 탐색 O(1) vs 삽입 O(1)의 상호 트레이드오프
- 포인터와 동적 메모리 할당 — 연결 리스트가 성립하는 하드웨어적 기반

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터와 메모리 주소(포인터)를 하나로 묶은 노드(Node)들의 체이닝을 통해 동적 크기를 지원하는 선형 자료구조이다.
> 2. **가치**: 크기 가변성과 O(1)의 삽입/삭제 오버헤드(위치 파악 제외)를 제공하여, 빈번한 데이터 갱신이 일어나는 동적 메모리 환경의 기반을 제공한다.
> 3. **판단 포인트**: 특정 인덱스로의 고속 랜덤 접근(Random Access)이 불가하므로 조회 중심 시스템에는 배열을, 삽입/삭제 중심 큐/버퍼 구현에는 연결 리스트를 채택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배열(Array) 한계 극복 원리 확인 | 물리적 불연속성과 논리적 연속성의 분리 (포인터 기반) | 탐색 성능이 배열보다 우수하다고 오답 서술 |
| 자료구조 선택의 Trade-off 기준 | Random Access 불가 (O(N) 탐색 지연), 포인터 오버헤드 | 단일/이중/환형 연결 리스트의 종류만 나열하는 것 |

> 요약: 연결 리스트는 메모리 제약을 극복하고 쓰기(Write) 효율을 높이는 대신 읽기(Read) 성능과 추가 메모리를 희생하는 극단적 Trade-off 구조다.

## Ⅰ. 개요 및 필요성

- 정의: 데이터 필드와 링크(포인터) 필드로 구성된 노드들이 체인 형태로 논리적 연속성을 갖는 동적 자료구조
- 배경: 연속 메모리 블록을 요구하는 배열의 단편화 한계 및 중간 삽입/삭제 시 발생하는 O(N) 밀어내기 연산 병목
- 필요성: 시스템 버퍼, 해시 충돌 체이닝 등 크기를 예측할 수 없는 동적 데이터 집합을 밀리초 내 관리하기 위해 필수

## Ⅱ. 구조 및 구성요소

```text
[Head Pointer] -> [Data | Next Pointer] -> [Data | Next Pointer] -> [Data | Null]
                    (Node 1)                  (Node 2)                 (Node N)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 노드 (Node) | 데이터와 다음 포인터를 담는 논리적 데이터 블록 단위 | 운영체제로부터 런타임에 동적 할당 |
| 데이터 필드 | 실제 밸류(Value) 저장 공간 | 다양한 데이터 타입 수용 가능 |
| 포인터 필드 | 다음 노드의 물리적 메모리 주소 저장 | 이중 연결의 경우 Prev 포인터 추가 할당 |
| 헤드 (Head) | 연결 리스트 탐색의 유일한 진입점 | 소실 시 전체 데이터 접근 불가(메모리 누수) |

> 요약: 각 노드는 물리적으로 흩어진 메모리에 배치되며, 포인터를 통해서만 논리적 인덱스 순서가 성립된다.

---

## Ⅲ. 동작원리 및 중간 삽입 흐름도

```text
삽입 요청 -> 타겟 앞 노드(P) 탐색 -> 새 노드(N) 동적 생성 
            -> N의 포인터가 P의 다음 노드를 가리킴 -> P의 포인터가 N을 가리킴 -> 완료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 진입 및 위치 탐색 | Head부터 순차 탐색하여 삽입 기준점 노드 확보 |
| 2 | 동적 메모리 할당 | OOM(Out of Memory) 방지를 위한 메모리 풀 가용성 체크 |
| 3 | 포인터 링크 재배치 | 새 노드의 포인터 갱신을 반드시 선행 |
| 4 | 연결 확정 및 GC 방지 | 이전 노드와의 포인터 결합 완료 후 참조 무결성 검증 |

> 요약: 노드 삽입 자체는 O(1)이지만, 올바른 포인터를 갱신하려면 삽입 위치까지 도달하는 O(N) 탐색 비용이 선행된다.

## Ⅳ. 배열과 연결 리스트 심화 비교

| 비교 축 | 배열 (Array) | 연결 리스트 (Linked List) | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 접근 (Read) | 인덱스 랜덤 접근 우수 O(1) | 헤드부터 순차 탐색 O(N) | 데이터 조회가 90% 이상인 경우 배열 |
| 삽입/삭제 (Write) | 최악 O(N) (데이터 시프트 연산) | 포인터 변경만으로 달성 O(1) | 빈번한 요소 교체 시 연결 리스트 |
| 메모리 할당 구조 | 선언 시 컴파일 타임 정적 할당 | 런타임 단위 동적 불연속 할당 | 메모리 단편화 상태 및 가용 풀 제약 |
| 오버헤드 특성 | 미사용 예약 공간 낭비 발생 | 포인터 유지를 위한 메모리 오버헤드 | 데이터 크기 대비 포인터 크기 비율 |

> 요약: 빈번한 데이터 추가/제거가 일어나는 큐 시스템은 연결 리스트를, 고속 인덱스 조회가 필요한 통계 시스템은 배열을 채택한다.

## Ⅴ. 심화 적용 및 파생 적용 (단일 vs 이중 vs 환형)

| 리스크 | 발생 원인 | 대응 기법 | 확인 지표 |
|:---|:---|:---|:---|
| 단방향 탐색 지연 | 노드 중간에서 이전 노드 추적 불가 | Prev 포인터를 추가한 이중 연결 리스트(Doubly)로 양방향 이동 확보 | 순차 역방향 조회 처리량 |
| 꼬리 탐색 지연 | 큐(Queue) 구현 시 마지막 노드 추적 부하 | 꼬리가 헤드를 가리키는 환형(Circular) 및 Tail 포인터 적용 | 끝단 갱신 응답 시간 |
| 캐시 지역성 저하 | 노드 간 불연속 할당으로 인한 캐시 미스 | 다수 노드를 하나의 연속 블록으로 묶는 Unrolled Linked List 적용 | 캐시 적중률(Hit Ratio) |

> 요약: 단일 연결 리스트의 단방향 제약을 극복하기 위해 메모리를 약간 투자하여 이중/환형 연결 등으로 튜닝한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LRU 캐시 교체 알고리즘 구현: 해시 테이블(고속 조회)과 이중 연결 리스트(순서 관리)를 결합하여 O(1) 속도로 오래된 데이터 식별/축출
2. OS 스케줄링 및 프로세스 관리: 단편화된 가용 메모리 블록 리스트 관리와 PCB(Process Control Block) 기반 큐 구현
3. 해시 충돌 체이닝 방어: 키 해시 값이 일치하는 잉여 레코드를 연결 리스트로 매달아 해시 테이블 붕괴 방지

**결론 (2줄):**
- 기술사 판단: 연결 리스트는 동적 확장이 자유로우나 캐시 지역성 측면에서 불리하므로 최신 시스템에서는 가변 배열과의 벤치마크 후 도입을 결정해야 한다.
- 향후 방향: 대용량 분산 시스템에서는 포인터 참조 한계를 극복하기 위해 순차적 로그(Log-structured) 형태나 압축 배열 구조가 연결 리스트를 대체하는 추세다.
