# 연결 리스트 (Linked List)

## 1. 개요

- **정의/개념**: 연결 리스트는 각 노드가 데이터와 다음 노드 참조를 가지고, 포인터 연결로 원소의 논리적 순서를 표현하는 선형 자료구조이다.
- **배경/필요성**: 배열은 중간 삽입·삭제 시 원소 이동과 재할당 비용이 발생하므로, 노드 참조 변경만으로 순서를 유연하게 수정할 수 있는 구조가 필요하다.

연결 리스트는 위치를 알고 있는 삽입·삭제에는 유리하지만, 임의 접근과 캐시 효율은 배열보다 불리하다.

## 2. 특징 및 비교

| 구분 | 배열(Array) | 연결 리스트(Linked List) |
|---|---:|---:|
| 메모리 배치 | 연속 공간 | 비연속 가능 |
| 임의 접근 | `O(1)` | `O(n)` |
| 중간 삽입·삭제 | 원소 이동으로 `O(n)` | 위치 참조 확보 시 `O(1)` |
| 캐시 지역성 | 높음 | 낮을 수 있음 |
| 공간 오버헤드 | 낮음 | 포인터 저장공간 필요 |

- 단일 연결 리스트는 구조가 단순하지만 이전 노드 접근이 어렵다.
- 이중 연결 리스트는 양방향 순회와 삭제가 쉽지만 포인터 오버헤드가 증가한다.
- 원형 연결 리스트는 라운드 로빈처럼 끝과 시작이 이어지는 처리에 적합하다.

## 3. 구성요소/구조

```text
Head -> [Data | Next] -> [Data | Next] -> [Data | Next] -> null
```

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Head | 첫 노드를 가리키는 참조 | 접근 시작점 |
| Node | 데이터와 링크를 가진 저장 단위 | 데이터+포인터 |
| Next | 다음 노드 주소 | 순차 접근 |
| Prev | 이중 리스트의 이전 노드 주소 | 역방향 이동·삭제 |
| Tail | 마지막 노드 참조 | 끝 삽입 최적화 |

삽입 시 새 노드의 링크를 먼저 설정한 뒤 기존 노드의 링크를 변경해야 연결 손실을 막을 수 있다.

## 4. 문제점 및 개선방안

1. **임의 접근 비용**
   - 인덱스 기반 접근이 없어 특정 위치 검색은 Head부터 순차 탐색해야 한다.
   - **개선방안**: 조회 중심 구조는 배열, 동적 배열, 균형 트리로 전환한다.

2. **포인터 오버헤드와 캐시 비효율**
   - 노드가 메모리에 흩어지면 포인터 저장공간과 캐시 미스가 증가한다.
   - **개선방안**: 메모리 풀, 배열 기반 리스트, 노드 압축을 적용한다.

3. **참조 갱신 오류**
   - 삽입·삭제 순서가 틀리면 연결 단절, 순환 오류, 메모리 누수가 발생한다.
   - **개선방안**: 더미 노드, 표준 삽입·삭제 템플릿, 누수 검사를 적용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| LRU 캐시 | 해시 테이블과 이중 연결 리스트를 결합해 조회와 순서 갱신 처리 | hit ratio, 갱신 지연 |
| 운영체제 큐 | 준비 큐, 대기 큐, free list에 노드 삽입·삭제 적용 | 삽입·삭제 지연, 누수 여부 |
| 그래프 표현 | 인접 리스트로 정점별 연결 간선 저장 | 메모리 사용량, 순회 시간 |

## 6. 결론

연결 리스트는 동적 크기 변화와 위치 기반 삽입·삭제에 강한 자료구조이다. 다만 `O(1)` 삽입·삭제는 위치 참조 확보가 전제이며, 검색 중심 업무에서는 배열·트리 구조와 비교해야 한다.
