## Ⅰ. 개요
- **개요**: 연결 리스트는 각 노드가 데이터와 다음 노드의 포인터를 함께 저장해 사슬처럼 이어 붙인 선형 자료구조임
- **배경/필요성**: 배열은 크기가 고정되고 중간 삽입·삭제 시 뒤 원소를 모두 밀어야 해 $O(N)$이 걸리므로, 필요할 때마다 메모리를 하나씩 확보하고 포인터로만 순서를 이어 삽입·삭제를 $O(1)$에 처리하는 구조가 필요함
- **출제 의도**: 노드·포인터 구조의 이해, 삽입·삭제가 $O(1)$이 되는 조건 판단, 배열과의 구조적 차이에 근거한 선택 능력을 확인함
- **답안 방향**: 노드 구성 → 포인터 조작에 의한 삽입·삭제 원리 → 배열과의 구조 비교 → 실무 적용 판단 순으로 전개

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 자료구조 구조·동작 설명 요구 | 노드 구성, 포인터 방향, 삽입·삭제 $O(1)$ 성립 조건 | 임의 접근 $O(N)$ 언급 누락, 배열과의 무근거 비교 |

> 요약: 노드·포인터 조작으로 삽입·삭제 비용을 낮추는 대신 임의 접근을 포기한 구조라는 점이 판단의 축임

## Ⅱ. 구조 및 구성요소
```text
[단일 연결 리스트]
head -> [A|next] -> [B|next] -> [C|next] -> null

[이중 연결 리스트 + 더미 노드]
head(dummy) <-> [A|prev|next] <-> [B|prev|next] <-> [C|prev|next] <-> tail(dummy)

[원형 연결 리스트]
head -> [A] -> [B] -> [C] -+
         ^-------------------+
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 노드(Node) | `data`와 포인터를 함께 담는 기본 단위 | 보물찾기의 한 장소 — 내용물 + 다음 힌트 |
| 단일 연결 리스트 | `next` 포인터만 보유, 한 방향 순회만 가능 | 편도 기차 |
| 이중 연결 리스트 | `prev`·`next` 양쪽 보유, 양방향 순회 및 삭제 시 이전 노드 즉시 접근 | 양방향 기차 |
| 원형 연결 리스트 | 마지막 노드가 첫 노드를 가리켜 끝이 없는 순환 구조 형성 | 회전목마 |
| head/tail 포인터 | 리스트의 시작/끝 노드를 가리키는 참조 | 기차의 맨 앞·맨 뒤 칸 |
| 더미 노드(Sentinel) | 데이터 없이 경계만 표시해 첫/끝 삽입·삭제의 예외 분기를 제거 | 실제 내용 없는 표지판 |

> 요약: 포인터의 방향 수(단일/이중)와 순환 여부(원형)가 연결 리스트 변형을 가르고, head/tail·더미 노드는 경계 처리를 단순화함

## Ⅲ. 동작원리 및 흐름도
```text
[삽입] B, C 사이에 X 삽입
인접 노드 확보(B, C) -> X.next=C, X.prev=B -> B.next=X, C.prev=X -> 삽입 완료

[삭제] X 제거
대상 노드 확보(X) -> B.next=C, C.prev=B -> X 메모리 해제 -> 삭제 완료
```

- 1단계 인접 노드 확보: 삽입·삭제 위치의 앞뒤 노드에 대한 참조를 얻음(위치를 모르면 순회로 $O(N)$ 선행)
- 2단계 포인터 재배치: 신규 노드는 인접 노드를 가리키도록, 인접 노드는 신규 또는 다음 노드를 가리키도록 갱신
- 3단계 사슬 반영: 삽입은 새 노드를 사슬에 끼우고, 삭제는 대상 노드를 사슬에서 끊음
- 4단계 경계 확인: head/tail 및 더미 노드 갱신 여부를 확인하고 종료

> 요약: 삽입·삭제는 인접 노드 참조를 이미 가지고 있을 때만 $O(1)$이며, 위치 탐색이 필요하면 그만큼 $O(N)$이 추가됨

## Ⅳ. 특징
- 동적 크기: 노드 단위로 메모리를 그때그때 확보해 최대 크기를 미리 정할 필요가 없음
- 삽입·삭제 $O(1)$: 인접 노드 참조를 아는 경우 포인터 변경만으로 처리되어 원소 이동이 불필요함
- 임의 접근 불가: N번째 원소를 조회하려면 head부터 순회해야 하므로 $O(N)$이 소요됨
- 메모리 오버헤드: 데이터 외에 노드당 포인터 저장 공간(1~2개)이 추가로 소요됨
- 캐시 지역성 저하: 노드가 메모리 전역에 분산돼 배열 대비 캐시 미스가 늘어남

> 요약: 삽입·삭제 비용을 낮추는 대가로 임의 접근 성능과 캐시 효율을 내주는 구조임

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 연결 리스트 | 배열 | 선택 기준 |
|:---|:---|:---|:---|
| 메모리 배치 | 비연속, 포인터로 연결 | 연속 | 캐시 효율이 우선이면 배열 |
| 임의 접근 | $O(N)$ | $O(1)$ | 인덱스 조회가 빈번하면 배열 |
| 중간 삽입·삭제 | $O(1)$(위치를 알 때) | $O(N)$(시프트) | 삽입·삭제가 빈번하면 연결 리스트 |
| 크기 변경 | 노드 추가만 $O(1)$ | 재할당+복사 $O(N)$ | 크기가 가변적이면 연결 리스트 |

> 요약: 조회가 지배적인 워크로드는 배열, 삽입·삭제가 지배적이고 크기가 가변적인 워크로드는 연결 리스트가 유리함

**리스크·대응 (불릿):**
- 메모리 단편화: 노드 할당·해제가 빈번하면 힙 단편화가 누적됨 → 메모리 풀(Memory Pool)로 노드를 미리 할당해 대응
- 포인터 갱신 오류: 삽입·삭제 시 포인터 갱신 순서를 틀리면 리스트 단절이나 순환 참조가 발생함 → 더미 노드로 경계 분기를 없애 오류 지점을 축소
- 캐시 미스 누적: 대량 순회 시 캐시 미스로 실질 처리 시간이 늘어남 → 언롤드 연결 리스트(Unrolled Linked List)로 노드당 여러 원소를 저장해 완화

**도입 후 점검 지표 (불릿):**
- 조회 대비 삽입·삭제 비율: 조회 비중이 높아지면 배열·트리 구조로 전환 검토
- 노드 할당 실패율·힙 단편화율: 메모리 풀 적용 필요성 판단 근거
- 평균 순회 소요 시간: 캐시 미스 누적에 따른 지연 여부 확인

## Ⅵ. 실무 적용 및 결론
1. 단기: 삽입·삭제 빈도와 임의 접근 요구를 먼저 진단해 배열·연결 리스트 중 기본 정책을 결정
2. 중기: 이중 연결 리스트와 해시맵을 결합해 조회·순서 갱신을 모두 $O(1)$로 만드는 LRU 캐시형 구조를 적용
3. 장기: 대량 순회가 잦은 워크로드는 언롤드 연결 리스트로, 다중 스레드 환경은 CAS(Compare-and-Swap) 기반 락프리 연결 리스트로 고도화

- 기술사적 판단: 삽입·삭제가 지배적이고 크기가 가변적이면 연결 리스트, 조회가 지배적이면 배열을 선택하는 것이 구조 선택의 기본 기준임
- 기술사 제언: 해시 테이블의 체이닝(005)은 충돌 버킷을 연결 리스트로 관리하는 응용이며, 스택·큐·덱(007)은 본 구조 위에 LIFO·FIFO 정책을 얹은 것이므로, 노드·포인터 조작 자체는 본 파일을 기준으로 판단하고 응용별 세부 구현은 각 파일에서 확인함
