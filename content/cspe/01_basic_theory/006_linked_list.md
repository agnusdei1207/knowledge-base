## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 각 노드가 데이터와 다음 노드의 포인터를 가지며, 비연속 메모리에 동적 할당되는 선형 자료구조임 |
| **배경/필요성** | 배열의 고정 크기·삽입 삭제 O(n) 한계를 극복하기 위해 포인터 기반 동적 자료구조가 필요함 |
| **출제 의도** | 단일·이중·원형 연결 리스트의 구조와 배열 대비 장단점을 비교할 수 있는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| Head     | --> | Node     | --> | Tail/NULL|
| (시작)   |     | (Data+Ptr)|    | (끝)     |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 노드(Node) | 데이터 필드와 다음 노드를 가리키는 포인터로 구성된 기본 단위임 | 기차 객차(짐+연결고리) |
| Head 포인터 | 리스트의 첫 번째 노드를 가리키는 진입점임 | 기차 기관차 |
| Tail/NULL | 마지막 노드의 포인터가 NULL을 가리켜 끝을 표시함(원형은 Head로 회귀) | 기차 꼬리칸 |

> 요약: Head → Node(Data+Ptr) → … → NULL 구조로, 삽입·삭제 O(1)·탐색 O(n)의 특성을 가짐.

## Ⅲ. 절차
```
+------------+     +------------+
| 노드생성   | --> | 포인터연결  |
| (메모리할당)|     | (prev→new) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 삽입완료   | <-- | 기존연결   |
|            |     | 갱신       |
+------------+     +------------+
```

1. 노드 생성: 새 노드를 동적 할당하고 데이터를 저장함
2. 삽입 위치 탐색: Head부터 순회하여 삽입 위치의 이전 노드를 찾음(O(n))
3. 포인터 연결: 새 노드의 next를 이전 노드의 next로 설정함
4. 기존 연결 갱신: 이전 노드의 next를 새 노드로 변경하여 삽입을 완료함

> 요약: 노드 생성 → 위치 탐색 → 포인터 연결 → 기존 연결 갱신으로 O(1) 삽입을 수행함.

## Ⅳ. 문제점
- 순차 접근 한계: 인덱스 기반 랜덤 접근이 불가하여 탐색에 O(n)이 소요됨
- 포인터 오버헤드: 노드당 4~8바이트 포인터가 추가되어 소형 데이터에서 메모리 낭비가 큼
- 캐시 비친화적: 노드가 비연속 메모리에 분산되어 CPU 캐시 적중률이 배열 대비 저하됨

## Ⅴ. 개선방안
- (단기) 이중 연결 리스트: prev 포인터를 추가하여 역방향 탐색과 O(1) 삭제를 지원함
- (중기) 언롤드 연결 리스트: 노드당 복수 데이터를 저장하여 포인터 오버헤드와 캐시 미스를 줄임
- (장기) Skip List: 다단계 포인터를 추가하여 O(log n) 탐색을 구현하고 정렬 순서도 유지함

## Ⅵ. 전망
- OS 커널(리눅스 task_struct)·LRU 캐시·블록체인 등에서 연결 리스트가 핵심 자료구조로 활용되며, Lock-free 동시성 리스트가 멀티코어 환경에서 확산될 전망임
