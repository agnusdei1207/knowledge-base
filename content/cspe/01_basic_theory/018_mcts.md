## 미리 알고가기

- 상태: 게임판, 의사결정 단계, 현재 환경처럼 선택의 기준이 되는 정보임
- 행동: 현재 상태에서 선택 가능한 다음 수나 의사결정 옵션임
- 롤아웃: 트리 밖의 상태를 시뮬레이션 정책으로 끝까지 또는 일정 깊이까지 진행하는 과정임
- UCT: 탐색과 활용을 균형 있게 선택하기 위한 신뢰상한 기반 선택식임
- 보상: 시뮬레이션 결과를 수치화한 값이며 승패, 점수, 비용 감소 등이 될 수 있음

## Ⅰ. 개요

- **정의**: 몬테카를로 트리탐색(MCTS)은 의사결정 상태를 트리로 확장하면서 무작위 또는 정책 기반 시뮬레이션 결과를 누적해 가장 유망한 행동을 선택하는 탐색 알고리즘임. 상태 공간이 매우 크고 명확한 평가 함수는 없지만 다음 상태를 시뮬레이션할 수 있을 때, 탐색과 활용의 균형을 기준으로 제한 시간 안에서 좋은 선택을 찾기 위해 사용함.
- **배경/필요성**: MCTS는 모든 경우를 끝까지 탐색하지 않고 많이 이긴 경로와 아직 덜 확인한 경로를 함께 고려함. 따라서 시뮬레이터 품질, 롤아웃 정책, 반복 예산이 결과 품질을 결정함.
- **비유**: 여러 선택지를 모두 완벽히 분석하지 못할 때, 일부 길을 반복 체험해 본 기록을 쌓고 성과가 좋으면서 아직 덜 가 본 길도 적절히 확인하는 방식과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 확률적 탐색과 의사결정 알고리즘 이해 확인 | 선택, 확장, 시뮬레이션, 역전파, 탐색/활용 | 단순 몬테카를로와 혼동 |

> 요약: MCTS는 시뮬레이션 결과를 트리에 누적해 큰 상태 공간에서 제한 시간 내 유망 행동을 고르는 탐색 기법임.

## Ⅱ. 특징/비교

| 판단 기준 | 미니맥스 탐색 | 단순 몬테카를로 | MCTS |
|:---|:---|:---|:---|
| 탐색 구조 | 고정 깊이 게임 트리와 평가 함수 | 독립 표본 평균 | 시뮬레이션 결과를 트리에 누적 |
| 필요 조건 | 강한 휴리스틱 평가 함수 | 표본 생성 가능 | 상태 전이 시뮬레이터와 보상 |
| 선택 방식 | 최대/최소 플레이어 가정 | 무작위 평균 비교 | UCT 등으로 탐색/활용 균형 |
| 적합 상황 | 분기 수가 작고 평가식이 좋을 때 | 단순 추정 문제 | 분기 수가 크고 평가식이 약할 때 |
| 한계 | 큰 분기 수에 취약 | 구조적 학습이 약함 | 롤아웃 품질과 예산에 민감 |

> 요약: MCTS는 무작위 시뮬레이션을 트리 구조에 누적해 탐색 방향을 점점 개선한다는 점이 핵심 차이임.

- 반복 횟수가 늘수록 유망한 분기에 더 많은 시뮬레이션이 배정되는 anytime 알고리즘 성격을 가짐
- UCT의 탐색 계수는 검증된 선택과 미검증 선택 사이의 균형을 조절함
- 게임뿐 아니라 계획, 로봇 경로, 조합 최적화, 프로그램 합성에도 적용될 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 루트상태 | ---> | 선택/확장| ---> | 롤아웃   |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 방문/보상|      | UCT정책  |      | 역전파   |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 트리 노드 | 의사결정 상태를 나타내며 방문 수와 누적 보상을 저장함 | 경로별 기록판 |
| 행동 간선 | 상태에서 다음 상태로 이동하는 선택지를 표현함 | 갈림길 표지 |
| 선택 정책 | UCT처럼 어떤 자식 노드로 내려갈지 결정하는 규칙임 | 탐험 우선순위 |
| 롤아웃 정책 | 트리에 없는 상태를 빠르게 시뮬레이션하는 기본 행동 규칙임 | 모의 체험 방식 |
| 역전파 정보 | 시뮬레이션 보상을 경로상 노드 방문 수와 보상에 반영함 | 체험 후기 누적 |

> 요약: MCTS는 노드의 방문 수와 보상 통계를 이용해 다음 탐색 위치와 최종 행동을 결정하는 구조임.

- 노드 통계는 평균 보상만이 아니라 방문 수가 함께 있어야 탐색 불확실성을 판단할 수 있음
- 롤아웃이 너무 무작위이면 실제 좋은 행동을 구분하는 신호가 약해질 수 있음
- 병렬 MCTS는 같은 노드에 시뮬레이션이 몰리는 문제를 줄이는 정책이 필요함

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 선택     | ---> | 확장     | ---> | 시뮬레이션| ---> | 역전파   |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| UCT하강  |      | 새노드   |      | 보상계산 |      | 통계갱신 |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 현재 상태, 가능한 행동, 시뮬레이터, 보상 함수, 시간 또는 반복 예산을 정의함
2. **선택과 확장** - 루트에서 UCT 기준으로 내려가고, 아직 확장되지 않은 행동이 있으면 새 노드를 추가함
3. **시뮬레이션 수행** - 새 노드에서 롤아웃 정책으로 결과 상태까지 진행하고 보상을 계산함
4. **역전파와 행동 선택** - 경로상 노드의 방문 수와 누적 보상을 갱신하고 예산 종료 후 최다 방문 또는 최고 평균 보상 행동을 선택함

> 요약: MCTS 절차는 선택, 확장, 시뮬레이션, 역전파를 반복해 행동별 경험 통계를 축적하는 흐름임.

- 예산이 끝난 뒤 행동 선택 기준은 학습 중 선택 기준과 다를 수 있음
- 보상 범위가 일관되지 않으면 UCT 비교가 왜곡될 수 있어 정규화가 필요함
- 도메인 지식을 rollout policy나 prior로 넣으면 표본 효율이 좋아질 수 있음

## Ⅴ. 문제점

- **P1 롤아웃 품질 의존**: 시뮬레이션 정책이 실제 좋은 선택과 무관하면 누적 보상이 잘못된 방향으로 수렴할 수 있음
- **P2 계산 예산 민감성**: 상태 공간이 크거나 보상 신호가 희소하면 제한 시간 안에 충분한 방문 통계를 얻기 어려움
- **P3 탐색/활용 불균형**: UCT 계수나 prior가 부적절하면 이미 좋아 보이는 경로에 과도하게 몰리거나 너무 넓게 흩어짐

> 요약: MCTS의 품질은 롤아웃 신호, 반복 예산, 탐색/활용 조절이 맞물려 결정됨.

## Ⅵ. 개선방안

- **P1 대응**: 도메인 휴리스틱, 정책 네트워크, rollout cut-off와 value 추정을 결합해 보상 신호를 개선함 (확인: rollout 승률 예측력)
- **P2 대응**: 시간 예산 기반 anytime 실행, 트리 재사용, 병렬 시뮬레이션, progressive widening을 적용함 (확인: 방문 수와 응답시간)
- **P3 대응**: UCT 탐색 계수 튜닝, Dirichlet noise, prior 보정, 방문 수 기반 최종 선택 정책을 검증함 (확인: 탐색 분포와 성능)

> 요약: MCTS 개선은 시뮬레이션 품질을 높이고 예산 내 탐색 분포를 통제하는 방향으로 수행함.

## Ⅶ. 전망

- **향후 발전 방향**: MCTS는 강화학습, 정책/가치 네트워크, 시뮬레이터 기반 계획과 결합되어 큰 상태 공간 의사결정에 계속 활용됨
- **기술사적 판단**: MCTS를 단순 랜덤 탐색으로 설명하지 말고 트리 통계와 탐색/활용 균형으로 선택 이유를 제시해야 함
- **기술사 제언**: 답안에서는 네 단계 흐름과 함께 적용 전제인 시뮬레이터, 보상 함수, 계산 예산을 반드시 언급해야 함

> 요약: MCTS는 모델 기반 의사결정의 강력한 탐색 기법이며, 제한 예산 안에서 통계적 선택 품질을 높이는 것이 핵심임.
