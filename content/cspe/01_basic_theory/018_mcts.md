# 몬테카를로 트리탐색 MCTS (Monte Carlo Tree Search)

## 1. 개요

- **정의/개념**: 몬테카를로 트리탐색(Monte Carlo Tree Search, MCTS)은 상태 공간 트리에서 무작위 시뮬레이션 결과를 누적해 제한된 시간 안에 유망한 행동을 선택하는 탐색 기법이다.
- **배경/필요성**: 바둑·게임·계획 문제처럼 분기 수가 커서 전수 탐색이 어렵고 평가 함수를 설계하기 어려운 문제에서 탐색 예산을 효율적으로 배분할 필요가 있다.

## 2. 특징 및 비교

| 구분 | 미니맥스 | MCTS |
|---|---|---|
| 탐색 방식 | 가능한 수를 평가 함수로 전개 | 시뮬레이션 통계로 유망 수 탐색 |
| 필요 조건 | 평가 함수 품질 중요 | 시뮬레이션·보상 설계 중요 |
| 장점 | 명확한 게임 트리에 강함 | 큰 분기 수와 불완전 평가에 유리 |
| 한계 | 깊은 탐색 비용 큼 | 반복 수와 rollout 품질에 민감 |

MCTS는 탐색과 활용의 균형을 맞추며, 많이 방문한 노드의 평균 보상과 덜 탐색한 노드의 가능성을 함께 고려한다.

MCTS 선택은 분기 수, 탐색 예산, rollout 품질, 보상 설계, 탐색/활용 계수, 트리 재사용 가능성을 기준으로 판단한다.

이 기준은 네 단계가 반복되며 방문 수와 보상 통계를 누적할 때 유망 행동이 드러난다는 구조에서 나온다.

## 3. 구성요소/구조

| 단계 | 설명 | 핵심 포인트 |
|---|---|---|
| 선택(Selection) | 루트에서 유망한 자식 노드로 이동 | UCT 등 선택 정책 |
| 확장(Expansion) | 아직 방문하지 않은 행동을 새 노드로 추가 | 후보 확장 |
| 시뮬레이션(Simulation) | 임의 정책으로 끝까지 진행해 보상 계산 | rollout 품질 |
| 역전파(Backpropagation) | 보상을 경로 노드 통계에 반영 | 방문 수·평균 보상 |

```text
Selection -> Expansion -> Simulation -> Backpropagation -> Best Action
```

따라서 MCTS의 문제점은 트리 구조보다 rollout 품질, 보상 설계, 탐색 예산 배분이 흔들릴 때 먼저 나타난다.

## 4. 문제점 및 개선방안

1. **롤아웃 품질 의존**
   - 무작위 시뮬레이션이 실제 좋은 선택과 무관하면 통계가 잘못 수렴할 수 있다.
   - **개선방안**: 도메인 휴리스틱, 정책 네트워크, value 추정을 결합한다.

2. **계산 예산 민감성**
   - 제한 시간 안에 충분한 방문 통계를 얻기 어려울 수 있다.
   - **개선방안**: anytime 실행, 트리 재사용, 병렬 시뮬레이션을 적용한다.

3. **탐색/활용 불균형**
   - UCT 계수가 부적절하면 특정 경로에 과도하게 몰리거나 너무 넓게 흩어진다.
   - **개선방안**: 탐색 계수, prior, 최종 선택 정책을 검증한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 게임 AI | 제한 시간 안에 행동별 승률을 추정해 수 선택 | 승률, 방문 수 |
| 로봇 계획 | 시뮬레이터 기반 행동 후보 탐색 | 성공률, 계획 시간 |
| 의사결정 시뮬레이션 | 불확실한 경로를 샘플링해 정책 선택 | 평균 보상, 분산 |

## 6. 결론

MCTS는 큰 상태 공간에서 전수 탐색 대신 시뮬레이션 통계로 유망 행동을 고르는 탐색 기법이다. 성능은 분기 수, rollout 품질, 탐색 예산, 보상 설계, 탐색/활용 균형에 의해 결정된다.
