## 미리 알고가기

- 게임 트리: 가능한 행동과 상태 전이를 계층 구조로 표현한 탐색 공간임
- 롤아웃(Rollout): 특정 상태에서 종료 상태까지 가상으로 진행해 보상을 얻는 시뮬레이션임
- UCT(Upper Confidence Bounds applied to Trees): 평균 보상 활용과 방문이 적은 경로 탐색을 함께 반영해 자식 노드를 고르는 기준임
- 탐색과 활용: 새 경로 확인과 보상이 큰 경로 집중 사이의 균형임
- 역전파: 시뮬레이션 보상을 경로상의 노드 통계에 되돌려 반영하는 과정임
- 미니맥스: 상대의 최선 대응을 가정해 말단 상태의 평가값을 상위 노드로 전파하는 탐색 기법임
- 평가 함수: 비말단 게임 상태의 가치를 수치로 추정하는 함수임

## 작성 근거(검토용)

- **개요 구성**: 기출 키워드이므로 MCTS의 4단계와 노드 통계 기반 선택을 정의에 함께 넣음
- **Ⅱ. 특징 선정**: 평가 함수 의존 완화·중간 결과 반환·UCT 균형·롤아웃 품질은 MCTS 선택 이유를 설명함
- **Ⅲ. 비교축 선정**: 가치 계산, 탐색 범위, 주요 위험은 미니맥스와 MCTS의 선택을 가름
- **Ⅳ. 구조 선정**: 선택 정책, 확장 규칙, 롤아웃 정책, 통계 저장소, 역전파 로직은 4단계 동작에 필요한 구성임
- 롤아웃 편향과 실시간 예산은 MCTS 적용 시 품질과 응답 시간을 좌우함

## Ⅰ. 개요

- **정의/개념**: MCTS는 선택·확장·시뮬레이션·역전파를 반복해 노드별 보상 통계로 유망한 행동을 고르는 트리 탐색 기법임
- **배경/필요성**: 제한된 시간에 유망 경로를 탐색하기 위해 계산 자원 배분 기준이 필요함

## Ⅱ. 특징

- 비말단 상태의 정교한 평가 함수가 없어도 롤아웃 보상 평균으로 행동 가치를 추정함
- 시간이 허용되는 만큼 반복하고 중간에도 현재까지의 최선 행동을 반환함
- UCT로 탐색과 활용의 균형을 조절함
- 롤아웃 정책 품질이 통계 수렴 속도와 선택 품질을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 미니맥스 (Minimax) | MCTS |
|:---|:---|:---|
| 가치 계산 | 평가 함수로 계산한 상태값 | 롤아웃의 평균 보상 |
| 탐색 범위 | 지정 깊이까지 가능한 수 탐색 | 시간 예산 내 유망 경로 집중 탐색 |
| 주요 위험 | 평가 함수 오차의 상위 전파 | 롤아웃 편향에 따른 선택 왜곡 |

> 요약: 지정 깊이의 상태를 평가하며 탐색하면 미니맥스, 제한 시간에 롤아웃 보상으로 유망 경로를 탐색하면 MCTS를 적용함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 선택 정책 | 탐색 통계 기반의 다음 자식 노드 선택 |
| 확장 규칙 | 미시도 행동의 자식 노드 추가 |
| 롤아웃 정책 | 새 상태부터 종료 상태까지 행동을 선택하는 규칙 |
| 통계 저장소 | 노드별 방문 수와 보상 통계 저장 |
| 역전파 로직 | 롤아웃 보상의 루트 경로 반영 |

> 요약: MCTS는 롤아웃 결과로 노드 통계를 갱신하고 다음 탐색 경로를 다시 선택하는 반복 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
UCT로 노드 선택 → 미시도 행동 확인
                 ├─ 있음 → 자식 확장
                 └─ 없음 → 선택 계속
                              ↓
                       롤아웃 → 보상 역전파
                                      ↓
                                탐색 예산 판정
                         ├─ 남음 → 루트에서 반복
                         └─ 소진 → 최종 행동 선택
```

1. **노드 선택**: 루트에서 UCT가 높은 자식을 따라 확장 가능한 노드까지 내려감
2. **자식 확장**: 아직 시도하지 않은 행동 하나를 자식 노드로 추가함
3. **롤아웃 수행**: 기본 정책으로 종료 상태까지 진행해 보상을 얻음
4. **통계 역전파**: 경로상의 방문 수와 누적 보상을 갱신함

> 요약: MCTS는 롤아웃 보상을 노드 통계로 되돌려 다음 선택 기준을 계속 갱신함.

## Ⅵ. 실무 사례

1. GUI 회귀 테스트 생성기는 새로운 화면 상태·코드 경로에 보상을 주고, 커버리지 증가량과 탐색 시간으로 UCT 탐색 계수를 조정함
2. 장애 복구 시뮬레이터는 재시작·우회·페일오버 순서를 롤아웃하고, 복구 성공률과 계획 지연으로 탐색 시간 예산을 정함

## Ⅶ. 결론

- MCTS는 모의 실행을 반복해 유망한 행동에 탐색을 집중하며, 새 경로 탐색과 검증된 경로 활용의 균형이 필요함
- 즉시 결정해야 하는 시스템은 탐색 시간 한도와 실제 상태를 훼손하지 않는 시뮬레이터를 두고, 결과 편차가 크면 사람 승인 후 실행해야 함
