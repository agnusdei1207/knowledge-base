# 018. 몬테카를로 트리탐색 MCTS (Monte Carlo Tree Search) [출제:135회]

## 미리 알고가기

- **게임 트리 (Game Tree)**: 게임의 가능한 모든 상태와 전이를 나타낸 트리 구조임
- **평가 함수 (Evaluation Function)**: 게임의 특정 상태가 얼마나 유리한지를 수치화하는 함수이나, 바둑과 같은 복잡한 게임에서는 설계가 매우 어려움
- **UCT (Upper Confidence Bound applied to Trees)**: 탐색(Exploration)과 활용(Exploitation)의 균형을 맞추기 위해 사용되는 노드 선택 공식임

## 1. 개요

- **정의/개념**: 몬테카를로 트리 탐색(Monte Carlo Tree Search, MCTS)은 전체 탐색 공간을 조사하는 대신, 무작위 시뮬레이션을 통해 얻은 승률 통계를 기반으로 유망한 자식 노드를 집중 탐색하여 최적의 수를 찾는 알고리즘임
- **배경/필요성**: 바둑(Go)과 같이 상태 공간이 방대하고 평가 함수 설계가 불가능에 가까운 경우, 전통적인 미니맥스(Minimax) 탐색은 한계가 있음. MCTS는 도메인 지식 없이도 시뮬레이션 결과만으로 승률을 추정하여 복잡한 게임 트리 문제를 해결함

## 2. 특징 및 비교

MCTS는 고정된 깊이를 탐색하는 방식이 아닌, 시간에 따라 탐색 범위를 유동적으로 확장하는 'Anytime Algorithm'의 특성을 가짐.

| 비교 항목 | 미니맥스 (Minimax) | 몬테카를로 트리 탐색 (MCTS) |
|:---|:---|:---|
| **판단 근거** | **결정론적 평가 함수** 점수 | **확률적 시뮬레이션** 승률 통계 |
| **탐색 방식** | 고정 깊이 전수 조사 | 유망한 경로 집중 탐색 |
| **성능 특징** | 평가 함수의 정확도에 의존 | **시뮬레이션 횟수**에 비례하여 향상 |
| **중단 시점** | 탐색 완료 전까지 해답 도출 곤란 | **언제든 현재 최적해 반환 가능 (Anytime)** |
| **대표 사례** | 체스, 오목 (상태 공간 작음) | 바둑, 복잡한 실시간 전략 게임 |

> 요약: 규칙이 단순하고 상태가 적으면 미니맥스가 정교하며, 불확실성이 크고 상태가 방대하면 MCTS가 압도적임.

## 3. 구성요소/구조

MCTS는 '선택-확장-시뮬레이션-역전파'의 4단계 사이클을 반복하며 트리를 성장시킴.

- **구성요소**:
  - **UCT 수식**: $UCB1 = \bar{x}_i + c \sqrt{\frac{\ln N}{n_i}}$ (승률 + 탐색 가중치)
  - **Selection Policy**: 트리 내부에서 다음 노드를 선택하는 규칙
  - **Simulation (Rollout)**: 노드 하위에서 게임 끝까지 무작위로 진행하는 과정
  - **Backpropagation**: 시뮬레이션 결과를 경로 상의 모든 부모에게 전달

- **4단계 반복 구조 (원리/흐름도)**:

```text
[MCTS Loop]
1. Selection  : 루트부터 UCT가 가장 높은 자식 노드를 따라 리프까지 내려감
2. Expansion  : 리프 노드에서 새로운 자식 노드를 추가함
3. Simulation : 추가된 노드에서 무작위(Rollout)로 게임을 끝까지 진행함
4. Backprop   : 결과(승/패)를 루트까지 거슬러 올라가며 노드 정보(n, w) 갱신
```

1. **선택**: 이미 검증된 좋은 수(활용)와 아직 덜 가본 수(탐색) 사이의 균형을 UCT로 조절함
2. **확장**: 탐색되지 않은 새로운 상태를 트리 구조에 편입시킴
3. **시뮬레이션**: 복잡한 연산 없이 무작위 대국으로 승률을 표본 조사함
4. **역전파**: 하위의 결과가 상위 선택에 영향을 주도록 통계치를 누적함

## 4. 문제점 및 개선방안

1. **무작위 시뮬레이션의 부정확성**: 롤아웃 시 너무 무작위로만 두면 실제 고수들이 두는 양상과 멀어져 통계적 왜곡이 발생함
   - **개선방안**: 알파고(AlphaGo)처럼 딥러닝 **정책망(Policy Network)**을 도입하여 실력 있는 수 위주로 시뮬레이션하거나, **가치망(Value Network)**으로 시뮬레이션 자체를 대체함 (확인: 착수 일치율 및 승률 예측 오차)

2. **수렴 속도 및 자원 소모**: 유망한 수에 도달하기까지 수만 번의 시뮬레이션이 필요하여 실시간 대응이 늦어질 수 있음
   - **개선방안**: 이전 수에서 생성된 트리 정보를 재사용(Tree Reuse)하거나, 여러 CPU/GPU 코어에서 시뮬레이션을 병렬로 수행함 (확인: 초당 시뮬레이션 횟수)

3. **함정 수(Trap)에 취약**: 특정 경로의 깊은 곳에 단 하나의 패배 수가 숨겨져 있는 경우, 평균 승률 기반의 MCTS는 이를 놓치고 해당 경로를 선택할 위험이 있음
   - **개선방안**: 탐색 계수 $c$를 조정하여 탐색 비중을 높이거나, 특정 깊이 이상에서는 결정론적 탐색(미니맥스 등)을 혼용함 (확인: 특정 상황에서의 오판율)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 인공지능 바둑 (AlphaGo) | MCTS를 골격으로 하되 신경망을 통해 선택과 시뮬레이션을 최적화 | 프로 기사와의 승률, 탐색 효율 |
| 자율주행 경로 계획 | 미래의 다양한 교통 상황을 시뮬레이션하여 사고 확률이 가장 낮은 경로 결정 | 사고 회피율, 경로 부드러움 |
| 공정 스케줄링 | 수많은 작업 순서 조합 중 최적의 완료 시간(Makespan)을 가진 조합 탐색 | 공정 완료 시간, 장비 가동률 |
| 신약 후보 물질 탐색 | 분자 구조의 다양한 조합 중 결합력이 높을 것으로 예상되는 구조를 시뮬레이션으로 식별 | 유효 물질 발견 확률, 시뮬레이션 비용 |

> 요약: 정해진 시간 내에 최적에 가까운 의사결정을 내려야 하는 거대 탐색 공간 문제의 표준 해법임.

## 6. 결론

몬테카를로 트리 탐색은 무지(Ignorance)로부터 통계적 통찰을 이끌어내는 현대 알고리즘의 정수임. 기술사는 MCTS가 단순한 게임 알고리즘을 넘어, 복잡한 비즈니스 의사결정이나 물류 최적화 등 불확실성이 큰 환경에서 '지속적으로 답을 개선해나가는' 유연한 도구임을 이해해야 함.

특히 신경망과의 결합(Deep MCTS)은 직관과 논리적 탐색을 결합한 인공지능의 새 지평을 열었음. 실무 적용 시에는 탐색과 활용의 균형을 결정하는 UCT 파라미터 튜닝과, 도메인 특성을 반영한 효율적인 시뮬레이션 모델 설계 능력이 성공의 관건임.
