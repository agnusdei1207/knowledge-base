## 미리 알고가기

- 게임 트리(Game Tree): 가능한 행동과 상태 전이를 계층 구조로 표현한 탐색 공간임
- 보상(Reward): 시뮬레이션이나 행동의 결과로 얻는 수치화된 성과값이며, MCTS는 이를 누적해 행동 가치를 추정함
- 롤아웃(Rollout): 특정 상태에서 종료 상태까지 가상으로 진행해 보상을 얻는 시뮬레이션임
- UCT(Upper Confidence Bounds applied to Trees): 평균 보상 활용과 방문이 적은 경로 탐색을 함께 반영해 자식 노드를 고르는 기준임
- 탐색과 활용(Exploration and Exploitation): 새 경로 확인과 보상이 큰 경로 집중 사이의 균형임
- 역전파(Backpropagation): 시뮬레이션 보상을 경로상의 노드 통계에 되돌려 반영하는 과정임
- 미니맥스(Minimax): 상대의 최선 대응을 가정해 말단 상태의 평가값을 상위 노드로 전파하는 탐색 기법임
- 평가 함수(Evaluation Function): 비말단 게임 상태의 가치를 수치로 추정하는 함수임

## 작성 근거(검토용)

- **방향성**: MCTS는 평가 함수 없이도 롤아웃 평균으로 행동 가치를 추정하므로, 분기 수가 많거나 좋은 평가 함수를 설계하기 어려운 게임에 적합하지만 UCT의 탐색·활용 균형과 충분한 시간 예산이 없으면 품질이 떨어짐
- **개요 구성**: 기출 키워드이므로 MCTS의 4단계와 노드 통계 기반 선택을 정의에 함께 넣음
- **Ⅱ. 특징 선정**: 평가 함수 의존 완화·중간 결과 반환·UCT 균형·롤아웃 품질은 MCTS 선택 이유를 설명함
- **Ⅲ. 비교축 선정**: 적용 기준, 탐색 범위, 주요 위험은 미니맥스와 MCTS의 선택을 가름
- **Ⅳ. 구조 선정**: 선택 정책, 확장 규칙, 롤아웃 정책, 통계 저장소, 역전파 로직은 4단계 동작에 필요한 구성임
- **Ⅵ·Ⅶ. 사례·결론 선정**: 롤아웃 편향과 실시간 예산은 MCTS 적용 시 품질과 응답 시간을 좌우해 실무 사례·결론의 판단축으로 씀
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 4단계 명칭과 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: MCTS는 선택·확장·시뮬레이션·역전파를 반복해 노드별 보상 통계로 유망한 행동을 고르는 트리 탐색 기법임
- **배경/필요성**: 제한된 시간에 유망 경로를 탐색하기 위해 계산 자원 배분 기준이 필요함

### 쉽게 이해하기 (학습용)
- 바둑에서 유망해 보이는 수를 골라 가상으로 여러 번 끝까지 대국해 보고 이긴 비율이 높은 수를 더 많이 시도하는 것과 같음

## Ⅱ. 특징

- 비말단 상태의 정교한 평가 함수가 없어도 롤아웃 보상 평균으로 행동 가치를 추정함
- 시간이 허용되는 만큼 반복하고 중간에도 현재까지의 최선 행동을 반환함
- UCT로 탐색과 활용의 균형을 조절함
- 롤아웃 정책 품질이 통계 수렴 속도와 선택 품질을 좌우함

### 쉽게 이해하기 (학습용)
- 바둑판 상황이 얼마나 유리한지 정확히 계산하는 공식이 없어도, 끝까지 여러 번 둬 보고 이긴 비율로 판단함
- 생각할 시간이 얼마가 주어지든, 중간에 멈춰도 그때까지 가장 좋아 보인 수를 답으로 내놓을 수 있음
- 안 가본 수도 가끔 시도해보고 이미 좋아 보인 수도 자주 시도하며 둘 사이 균형을 맞춤

## Ⅲ. 종류 및 비교

| 판단 기준 | 미니맥스 (Minimax) | MCTS |
|:---|:---|:---|
| 적용 기준 | 좋은 평가 함수가 있고 분기 수가 적어 깊이 제한 탐색이 가능할 때 | 평가 함수 설계가 어렵거나 분기 수가 많아 깊이 제한 탐색이 비현실적일 때 |
| 탐색 범위 | 지정 깊이까지 가능한 수 탐색 | 시간 예산 내 유망 경로 집중 탐색 |
| 주요 위험 | 평가 함수 오차의 상위 전파 | 롤아웃 편향에 따른 선택 왜곡 |

> 요약: 좋은 평가 함수와 적은 분기 수면 미니맥스, 평가 함수 설계가 어렵거나 분기 수가 많으면 MCTS를 적용함.

### 쉽게 이해하기 (학습용)
- 미니맥스는 정해진 수만큼 앞을 내다보며 각 수를 계산식으로 채점하지만, MCTS는 시간이 허락하는 만큼 유망한 수 위주로 실제 대국을 여러 번 굴려보고 그 결과로 채점함

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 선택 정책 | 탐색 통계 기반의 다음 자식 노드 선택 |
| 확장 규칙 | 미시도 행동의 자식 노드 추가 |
| 롤아웃 정책 | 새 상태부터 종료 상태까지 행동을 선택하는 규칙 |
| 통계 저장소 | 노드별 방문 수와 보상 통계 저장 |
| 역전파 로직 | 롤아웃 보상의 루트 경로 반영 |

> 요약: MCTS는 롤아웃 결과로 노드 통계를 갱신하고 다음 탐색 경로를 다시 선택하는 반복 구조임.

### 쉽게 이해하기 (학습용)
- 다음에 어느 수를 더 살펴볼지 고르는 기준(선택 정책), 아직 안 둬본 수를 새로 추가하는 규칙(확장 규칙), 그 수부터 끝까지 대충 둬보는 방식(롤아웃 정책), 각 수의 승률과 시도 횟수를 적는 장부(통계 저장소)가 함께 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
UCT로 노드 선택 → 미시도 행동 확인
                 ├─ 있음 → 자식 확장
                 └─ 없음 → 선택 계속
                              ↓
                       롤아웃 → 보상 역전파
                                      ↓
                                탐색 예산 판정
                         ├─ 남음 → 루트에서 반복
                         └─ 소진 → 최종 행동 선택
```

1. **노드 선택**: 루트에서 UCT가 높은 자식을 따라 확장 가능한 노드까지 내려감
2. **자식 확장**: 아직 시도하지 않은 행동 하나를 자식 노드로 추가함
3. **롤아웃 수행**: 기본 정책으로 종료 상태까지 진행해 보상을 얻음
4. **통계 역전파**: 경로상의 방문 수와 누적 보상을 갱신함

> 요약: MCTS는 롤아웃 보상을 노드 통계로 되돌려 다음 선택 기준을 계속 갱신함.

### 쉽게 이해하기 (학습용)
- 장부를 보고 유망한 수를 따라 내려가다 안 둬본 수를 하나 추가하고, 거기서부터 끝까지 대충 둬본 뒤 이긴 결과를 지나온 모든 갈림길의 장부에 되돌려 적는 일을 시간이 다 될 때까지 반복함

## Ⅵ. 실무 사례

1. GUI 회귀 테스트 생성기는 새로운 화면 상태에 높은 보상을 주어 아직 확인하지 않은 경로를 우선 탐색함
2. 장애 복구 시뮬레이터는 재시작·우회·페일오버 순서를 반복 실행해 복구 가능한 경로를 찾음

### 쉽게 이해하기 (학습용)
- 아직 눌러보지 않은 화면 버튼에 더 높은 점수를 줘서 우선 눌러보게 하거나, 장애가 났을 때 재시작·우회·전환 순서를 여러 번 가상으로 시도해 가장 잘 복구되는 순서를 찾는 것과 같음

## Ⅶ. 결론

- MCTS는 모의 실행을 반복해 유망한 행동에 탐색을 집중하며, 새 경로 탐색과 검증된 경로 활용의 균형이 필요함
- 즉시 결정해야 하는 시스템은 탐색 시간 한도와 실제 상태를 훼손하지 않는 시뮬레이터를 두고, 결과 편차가 크면 사람 승인 후 실행해야 함

### 쉽게 이해하기 (학습용)
- 모의 대국을 반복해 유망한 수에 탐색을 집중하는 방식이며, 즉시 결정해야 하는 시스템은 생각 시간에 한도를 두고 결과 편차가 크면 사람이 최종 확인해야 함
