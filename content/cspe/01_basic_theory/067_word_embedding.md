# 📖 【암기용】 개념 완전 이해

> 목적: 단어 임베딩을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **분포 가설**(Distributional Hypothesis) — "비슷한 문맥에 등장하는 단어는 비슷한 의미를 가진다" — 을 근거로, 단어를 저차원 **밀집 벡터**(Dense Vector)로 표현해 컴퓨터가 의미를 계산할 수 있게 만드는 기법이 단어 임베딩이다.
- **왜 필요한가**: 기존 One-hot 인코딩은 단어마다 사전 크기만큼의 차원이 필요해 계산이 비효율적이고(희소 문제), "사과"와 "배"의 거리가 "사과"와 "철도"의 거리와 똑같이 취급돼 의미 유사도를 전혀 표현하지 못했다.
- **핵심 직관**: 단어를 n차원 좌표 공간에 배치해, 자주 같은 문맥에서 등장하는 단어끼리는 가까운 좌표를 갖게 만든다 — 거리가 가까우면 의미가 비슷하다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| One-hot 인코딩 | 단어 하나를 사전 크기만큼의 차원 중 해당 위치만 1, 나머지는 0인 벡터로 표현 | 반 학생 전원 중 출석부 번호 하나만 손을 든 상태 |
| 희소 벡터(Sparse Vector) | 대부분의 값이 0인 벡터. One-hot의 결과물 | 대부분 빈칸인 출석부 체크리스트 |
| 밀집 벡터(Dense Vector) | 대부분의 값이 0이 아닌, 훨씬 작은 차원의 실수 벡터. 임베딩의 결과물 | 몸무게·키·나이처럼 값이 꽉 찬 프로필 수치 |
| 분포 가설(Distributional Hypothesis) | "비슷한 문맥에 등장하는 단어는 비슷한 의미를 가진다"는 임베딩 학습의 근거 이론 | 늘 같은 무리와 어울리는 사람은 성향도 비슷할 것이라는 추론 |
| CBOW(Continuous Bag of Words) | 주변 단어들로 중심 단어를 예측하도록 학습하는 Word2Vec 방식 | 앞뒤 문맥만 보고 빈칸에 들어갈 단어 맞히기 |
| Skip-gram | 중심 단어로 주변 단어들을 예측하도록 학습하는 Word2Vec 방식(CBOW의 반대) | 한 단어만 보고 앞뒤에 나올 법한 단어들을 짐작하기 |
| Negative Sampling | 전체 어휘를 대상으로 한 Softmax 대신, 정답 단어 + 무작위로 뽑은 오답 단어 몇 개만으로 학습해 연산량을 줄이는 기법 | 전교생과 비교하지 않고, 정답 후보와 무작위로 뽑은 소수 오답만 비교 |
| GloVe | 코퍼스 전체의 단어 동시 등장 횟수를 담은 행렬을 먼저 만들고, 이를 저차원으로 압축(행렬 분해)해 임베딩을 얻는 방식 | 전교생의 친분 관계표를 통째로 만든 뒤 요약하는 방식 |
| 동시 등장 행렬(Co-occurrence Matrix) | 단어 쌍이 정해진 윈도우 안에서 함께 등장한 횟수를 기록한 행렬 — GloVe의 입력 | 두 단어가 같이 등장한 횟수를 적어둔 표 |
| 코사인 유사도 | 두 임베딩 벡터의 방향이 얼마나 비슷한지 측정하는 지표 — 값이 클수록 의미가 유사 | 두 화살표가 같은 방향을 가리키는 정도 |
| FastText | 단어를 다시 n-gram(글자 조각)으로 쪼개 학습해, 사전에 없는 단어도 조각을 조합해 벡터를 만들 수 있게 한 Word2Vec의 확장판 | 모르는 단어라도 아는 음절 조각을 조합해 뜻을 추측 |

## 깊이 이해

### One-hot의 한계 — 수치로 이해
- 사전 크기가 10만이면 단어 하나의 One-hot 벡터는 10만 차원인데, 그중 딱 1개만 1이고 나머지 99,999개는 0이다. 단어 100만 개짜리 문서를 이 방식으로 표현하면 메모리와 연산량이 감당하기 어렵다.
- 게다가 임의의 두 단어(사과, 배) 벡터의 내적은 항상 0이다(서로 다른 위치에 1이 있으므로 직교). 사과-배 거리와 사과-철도 거리가 수학적으로 완전히 같아, "의미가 비슷하다"는 정보가 애초에 벡터 구조에 담길 수 없다.

### CBOW와 Skip-gram — 윈도우로 직접 확인
- 문장 "나는 오늘 아침에 밥을 먹었다"에서 윈도우 크기 2로 중심 단어를 "밥을"로 잡으면, 주변 단어는 앞 2개("오늘", "아침에") + 뒤 2개("먹었다", 문장끝)가 된다.
- CBOW는 이 주변 단어들(오늘, 아침에, 먹었다)을 입력으로 넣어 중심 단어("밥을")를 맞히도록 학습한다. Skip-gram은 반대로 "밥을" 하나를 입력해 오늘·아침에·먹었다를 각각 맞히도록 학습한다.
- Skip-gram은 학습 쌍이 더 많이 생겨(중심 1개당 주변 단어 수만큼) 저빈도 단어 학습에 유리하지만 느리고, CBOW는 여러 문맥을 평균 내 입력하므로 더 빠르지만 저빈도 단어 표현력이 떨어진다.

### Negative Sampling — 왜 필요하고 얼마나 빨라지나
- 원래 Word2Vec은 마지막에 전체 어휘(예: 10만 개) 중 정답 단어의 확률을 높이는 Softmax를 계산해야 해서, 한 번 학습할 때마다 10만 개 단어 전부에 대해 계산이 필요했다.
- Negative Sampling은 정답 단어 1개 + 무작위로 뽑은 오답(negative) 5~20개만 놓고 "이건 맞고 저건 아니다"를 이진 분류하듯 학습한다. 10만 개 대신 대략 6~21개만 계산하면 되므로 연산량이 수천분의 1로 줄어든다.

### 벡터 연산으로 의미 유추하기 — 수치 예시
- 학습된 임베딩이 2차원이라 가정하고 king=(0.8, 0.2), man=(0.3, 0.1), woman=(0.2, 0.7)이라면, king − man + woman = (0.8−0.3+0.2, 0.2−0.1+0.7) = (0.7, 0.8)이 된다.
- 이 결과 벡터 (0.7, 0.8)이 실제 queen의 벡터와 가장 가깝게(코사인 유사도가 가장 높게) 나오면 "왕 − 남자 + 여자 = 여왕"이라는 의미 관계가 벡터의 덧셈·뺄셈만으로 재현된 것이다. One-hot에서는 애초에 이런 연산 자체가 의미를 갖지 않는다.

### GloVe — 동시 등장 횟수로 직접 이해
- "ice"와 "solid"는 같은 문장에 자주 등장하지만, "solid"는 "steam"(수증기)과는 드물게 등장한다고 하자. 반대로 "gas"는 "steam"과 자주, "ice"와는 드물게 등장한다.
- 이때 비율 P(solid|ice)/P(solid|steam)은 크게 나오고, P(gas|ice)/P(gas|steam)은 작게 나온다 — 이 비율이 ice와 steam 각각의 성질(고체 vs 기체)을 구분하는 신호가 된다. GloVe는 이런 비율 정보를 저차원 벡터의 내적으로 근사하도록 학습해, Word2Vec처럼 문장을 하나씩 훑지 않고도 전체 코퍼스의 통계를 한 번에 반영한다 — 그래서 학습이 상대적으로 빠르다.

### 판별 원리 — 언제 무엇을 쓰나
- 학습 코퍼스가 크고 국소적 문맥(주변 몇 단어)의 관계가 중요하면 Word2Vec을 쓴다.
- 전체 코퍼스의 전역 통계(단어 동시 등장 경향)를 빠르게 반영하고 싶으면 GloVe를 쓴다.
- 동음이의어(배: 과일/선박/복부)처럼 문맥에 따라 뜻이 달라지는 단어를 구분해야 하면, 고정된 벡터 1개만 주는 Word2Vec/GloVe로는 한계가 있으므로 문맥마다 다른 벡터를 주는 BERT·ELMo 같은 동적 임베딩으로 넘어가야 한다.

## 연결 개념
- One-hot 인코딩 — 임베딩 이전의 희소 표현 방식, 임베딩이 극복한 대상
- 토큰화(066) — 임베딩에 넣기 전 문장을 단어·서브워드 토큰으로 분할하는 앞 단계
- BERT / GPT — 고정 벡터가 아니라 문맥에 따라 달라지는 동적 임베딩으로 동음이의어 한계를 해결
- 코사인 유사도 — 임베딩 벡터 간 의미적 유사도를 측정하는 핵심 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 단어 임베딩은 분포 가설 기반으로 단어를 저차원 밀집 벡터(Dense Vector)로 맵핑하는 자연어 표현 기술이다.
> 2. **가치**: 희소성(Sparsity) 문제를 해결하고, 코사인 유사도를 통한 단어 간 연산과 의미 추론을 가능하게 하여 NLP 모델 성능을 높인다.
> 3. **판단 포인트**: 국소 문맥은 Word2Vec, 전체 통계는 GloVe를 사용하며, 동음이의어 구분이 필수인 경우 사전학습 모델(BERT)로 전환해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기존 단어 표현 방식의 한계와 임베딩의 해결 기전 이해 | One-hot 인코딩의 차원의 저주, Word2Vec/GloVe 비교 | "성능이 좋다" 식 추상 서술 금지. 차원 축소 및 연산 가능성 명시 |
| Word2Vec 세부 알고리즘 구조 | CBOW vs Skip-Gram 방식 차이 | 구조를 반대로 쓰면 감점 |

> 요약: One-hot 인코딩의 차원 폭발 한계를 지적하고, Word2Vec과 GloVe의 생성 원리 차이를 명확히 비교해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 자연어 토큰을 의미적 유사도를 반영한 고정 길이의 밀집 실수 벡터로 변환하는 기법
- 배경: One-hot 인코딩은 단어 집합 크기만큼 차원이 증가(차원의 저주)하고 단어 간 직교(Orthogonal)성으로 의미 관계 표현 불가
- 필요성: 단어 간 코사인 유사도 계산과 차원 축소를 통해 후위 신경망 모델의 연산 복잡도 $O(N)$ 감소

---

## Ⅱ. 구조 및 구성요소

```text
입력 코퍼스 -> 토큰화/사전 구축 -> 임베딩 학습 (CBOW/Skip-Gram 등) -> 밀집 벡터 생성 -> 후위 태스크 활용
                                +-> 분포 가설 기반 가중치 갱신
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 입력 코퍼스 | 단어의 동시 등장 패턴 제공 | 대규모 말뭉치 필수 |
| 윈도우 크기 | 중심 단어 기준 주변 단어 참조 범위 | 보통 5~10 설정 |
| 투영층(Projection) | 입력 단어를 저차원으로 압축 | 활성화 함수 없는 선형 층 |
| 임베딩 행렬 | 학습 완료된 단어 벡터 집합 | $V \times D$ 차원 (V: 단어 수, D: 임베딩 차원) |

> 요약: 단어 임베딩은 코퍼스 내 윈도우 기반 동시 등장 패턴을 투영층을 통해 저차원 행렬로 압축 생성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Word2Vec 학습: 입력 단어 One-hot -> 가중치 행렬 W1 통과 -> 은닉층 압축 -> 가중치 W2 통과 -> 주변/중심 단어 예측 Loss 계산
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 코퍼스 수집 및 전처리 | 정제, 불용어 제거 |
| 2 | 학습 방식 설정 (CBOW / Skip-Gram) | 중심 단어 타겟 vs 주변 단어 타겟 |
| 3 | 순전파 및 오차 계산 | Softmax 기반 Cross-Entropy |
| 4 | 역전파 통한 행렬 업데이트 | Negative Sampling으로 최적화 |

> 요약: Word2Vec은 주변/중심 단어 예측 오차를 역전파하여 가중치 행렬을 갱신하는 방식으로 벡터를 학습한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 단어 간 유추 연산(Vector Math) 가능 | 시맨틱 검색, 추천 유사도 매칭 적용 |
| 한계 | OOV(Out of Vocabulary) 처리 불가 | FastText(Subword 방식) 도입 필요 |
| 비교 대상 | TF-IDF / One-hot | 희소 행렬 vs 밀집 행렬 |

> 요약: 벡터 덧셈/뺄셈을 통한 의미 연산이 가능하지만 미등록 단어(OOV) 문제 대응 설계가 별도로 필요하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Word2Vec | GloVe | 선택 기준 |
|:---|:---|:---|:---|
| 학습 방식 | 국소 윈도우 기반 신경망 예측 | 전체 코퍼스 동시 등장 행렬 분해 | 부분 문맥 중심 vs 전역 통계 중심 |
| 학습 속도 | 상대적으로 느림 (코퍼스 크기 비례) | 빠름 (행렬 분해) | 학습 자원 및 데이터 크기 |
| 적용 환경 | 문맥 기반 단어 관계 파악 | 전역적 통계 기반 관계 파악 | 태스크 특성에 따라 벤치마크 후 선택 |

> 요약: 국소 문맥의 유추 성능은 Word2Vec이, 전체 코퍼스 통계 반영 및 학습 속도는 GloVe가 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 동음이의어 문제 | 단어당 1개 벡터만 할당 | 문맥 임베딩(BERT, ELMo)으로 교체 | 동음이의어 분류 정확도 |
| OOV 발생 | 학습 코퍼스에 없는 단어 인입 | FastText(N-gram) 적용, Subword 토큰화 | OOV 비율 1% 미만 통제 |
| 학습 병목 | Softmax 연산 시 전체 단어 집합 계산 부하 | Negative Sampling, Hierarchical Softmax 적용 | 학습 소요 시간 및 메모리 |

> 요약: OOV와 동음이의어 한계는 FastText 및 사전학습 언어모델(PLM) 전환으로 대응한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 유사도 정확성 | 사람이 평가한 단어 유사도와 상관계수 0.7 이상 | WordSim-353 데이터셋 평가 |
| 유추 평가 | A:B = C:D 연산 정확도 | 구글 유추 테스트셋(Analogy Test) |
| 다운스트림 성능 | 분류, 개체명 인식 정확도 향상폭 | 기존 대비 F1-score 5%p 이상 개선 |

> 요약: 임베딩 품질은 단어 간 자체 유사도 테스트 및 후위 응용 모델의 성능 지표로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 추천 시스템: 상품명이나 검색어를 Word2Vec으로 임베딩하여 코사인 유사도 상위 10개 연관 상품을 노출한다.
2. OOV 대응 설계: 전문 용어가 많은 도메인에서는 FastText를 병행 도입하여 미등록 형태소 유입에 따른 예외 처리를 방어한다.
3. 연산 최적화: 수백만 단어 학습 시 Softmax 부하 방지를 위해 Negative Sampling(5~20개 샘플)을 적용해 훈련 소요 시간을 1/10 수준으로 단축한다.

**결론 (2줄):**
- 기술사 판단: 정적 단어 임베딩은 희소성 문제를 해결하나, 동음이의어 처리가 중요한 태스크는 트랜스포머 기반의 동적 문맥 임베딩(BERT)으로 이행해야 한다.
- 향후 방향: 단순 단어 수준을 넘어 문장(SentenceBERT), 문서, 그래프 구조까지 벡터화하는 범용 Representation Learning으로 진화하고 있다.
