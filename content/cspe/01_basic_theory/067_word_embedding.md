# 📖 【암기용】 개념 완전 이해

> 목적: 단어 임베딩을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 단어를 의미 관계가 반영된 실수 벡터로 표현하는 기법
- **왜 필요한가**: 원-핫 인코딩은 단어 간 유사도를 0으로만 보므로 "왕-남자+여자=여왕" 같은 의미 연산을 표현하지 못한다.
- **핵심 직관**: 비슷한 문맥에서 등장하는 단어는 좌표 공간에서도 가까운 점으로 배치한다.

## 깊이 이해
- **배경·문제의식**:
  - 전통적 Bag-of-Words는 차원이 vocabulary 크기만큼 커지고 희소 벡터가 된다
  - Word2Vec·GloVe는 100~300차원 dense vector로 의미 유사도와 문맥 관계를 압축한다
- **작동 원리**:
  - Word2Vec은 CBOW가 주변 단어로 중심 단어를 예측하고, Skip-gram이 중심 단어로 주변 단어를 예측한다
  - GloVe는 전체 말뭉치의 동시출현 행렬을 분해해 전역 통계까지 반영한다
- **비유**: 도시 지도를 만들 때 모든 장소를 이름 목록이 아니라 위도·경도 좌표로 표시하는 것과 같다.
  - 좌표가 가까우면 실제 의미 관계도 가까울 가능성이 높다
- **구체 예시**: 10억 토큰 말뭉치에서 Word2Vec 300차원 벡터를 학습하면 cosine similarity로 "자동차"와 "차량"이 0.75 이상, "자동차"와 "바나나"가 0.1 이하처럼 구분된다.
- **흔한 오해·주의점**:
  - Word2Vec은 문맥 독립 임베딩이므로 "bank"가 은행과 강둑 의미를 하나의 벡터에 섞는다
  - BERT 계열은 문맥별 벡터를 생성해 이 한계를 줄인다

## 연결 개념
- 토크나이징 — 임베딩의 입력 단위 결정
- 코사인 유사도 — 벡터 간 의미 유사도 측정
- BERT — 정적 임베딩을 문맥 임베딩으로 확장

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 단어 임베딩은 단어를 100~300차원 실수 벡터로 변환해 의미 유사도와 문맥 관계를 계산 가능하게 하는 표현 학습이다.
> 2. **가치**: 희소 원-핫 벡터를 dense vector로 치환해 검색, 분류, 추천에서 cosine similarity와 downstream F1 기준 평가를 가능하게 한다.
> 3. **판단 포인트**: Word2Vec은 국소 문맥 예측, GloVe는 전역 동시출현 통계, BERT는 문맥별 표현이라는 차이를 구분해야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 단어 의미를 벡터 공간에 배치하는 표현 기법
- 배경: 원-핫 인코딩은 차원 폭증과 의미 거리 부재 문제가 있어 NLP 모델의 일반화가 어려움
- 필요성: 의미 유사도 계산과 전이 학습의 기반이 되어 검색·분류·추천 시스템의 핵심 입력으로 쓰임

---

## Ⅱ. 구조 및 구성요소

```text
말뭉치 -> 토큰화 -> 학습 목표(CBOW/Skip-gram/GloVe) -> 임베딩 행렬
                      +-> negative sampling
                      +-> 유사도/다운스트림 평가
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 말뭉치 | 단어 문맥 통계 제공 | 최소 수백만~수십억 토큰 |
| 학습 목표 | 중심·주변 단어 예측 또는 행렬 분해 | CBOW, Skip-gram, GloVe |
| 임베딩 행렬 | token id를 dense vector로 매핑 | 100~300차원 일반 사용 |
| 평가 지표 | 유사도·분류 성능 검증 | cosine, analogy, F1 |

> 요약: 임베딩은 말뭉치 문맥 통계를 학습 목표로 압축해 단어별 dense vector 행렬을 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 문장 -> 주변 윈도우 추출 -> 단어 예측/행렬 분해
-> 벡터 업데이트 -> 유사도 계산 -> 업무 모델 적용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 토큰화·빈도 필터링 | min_count, vocabulary 크기 |
| 2 | 문맥 윈도우 구성 | window size 5~10 |
| 3 | 임베딩 학습 | loss 수렴, analogy accuracy |
| 4 | 다운스트림 적용 | 분류 F1, 검색 NDCG |

> 요약: 단어 주변 문맥을 학습 데이터로 만들어 벡터를 반복 갱신하고, 유사도와 업무 지표로 품질을 확인한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 의미 유사도와 벡터 연산 지원 | cosine 0.7 이상 유사어 후보 |
| 한계 | 다의어를 단일 벡터로 표현 | 문맥 독립, OOV 처리 제약 |
| 비교 대상 | 원-핫은 희소, BERT는 문맥별 dense vector | 데이터 규모·추론 비용 기준 |

> 요약: 단어 임베딩은 의미 계산을 가능하게 하지만 다의어와 OOV는 문맥 임베딩 또는 서브워드로 보완해야 한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 원-핫, TF-IDF | Word2Vec/GloVe dense vector | 의미 유사도 검색 필요 시 |
| 비용/성능 | 차원 수 vocabulary 전체 | 300차원 기준 메모리 절감 | vocabulary 100만, 벡터 1.2GB 내외 |
| 운영/위험 | 해석 용이 | 학습 말뭉치 편향 반영 | 편향 테스트와 재학습 주기 필요 |

> 요약: 의미 기반 검색·분류는 dense embedding을 선택하고, 설명 가능성이 핵심이면 TF-IDF와 병행한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 의미 편향 | 학습 말뭉치 성별·직업 편향 | WEAT, 편향 단어 필터링 | 편향 점수 기준선 이하 |
| OOV | 신조어·전문용어 미학습 | fastText n-gram, 사전 갱신 | OOV 1% 이하 |
| 다의어 혼합 | 단일 벡터 표현 | BERT 임베딩 전환 | WSD accuracy, F1 |

> 요약: 임베딩 운영은 편향·OOV·다의어 위험을 지표화하고 서브워드 또는 문맥 임베딩으로 보완한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 벡터 품질 | analogy accuracy 60% 이상, 유사어 Top-10 정밀도 | 표준 평가셋 |
| 업무 효과 | 검색 NDCG@10, 분류 F1 기준선 대비 +0.03 이상 | A/B 테스트 |
| 운영 통제 | 모델·말뭉치·vocabulary 버전 100% 추적 | MLflow, Git tag |

> 요약: 임베딩 품질은 단독 유사도 평가와 실제 업무 지표를 함께 확인해야 한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 도메인 말뭉치 1,000만 토큰 이상 확보 후 Word2Vec Skip-gram 300차원, window 5, negative 5 기준으로 학습함
2. 검색 적용 시 TF-IDF BM25와 embedding cosine을 결합하고 NDCG@10 기준선 대비 +0.03 이상일 때 전환함
3. 분기별 OOV·편향·유사어 Top-10 평가를 수행하고 모델 카탈로그에 말뭉치 출처와 학습 파라미터를 기록함

**결론 (2줄):**
- 기술사 판단: 도메인 용어 유사도 계산은 Word2Vec·GloVe, 문맥 의미 구분은 BERT 계열 임베딩을 선택함
- 향후 방향: 정적 단어 벡터는 경량 검색·추천에 남고, 고정밀 NLP는 문맥 임베딩과 벡터 DB로 전환됨
