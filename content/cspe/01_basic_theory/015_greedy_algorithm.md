## 미리 알고가기

- 국소 최적해(Locally Optimal): 현재 시점에서 가장 이익이 크거나 비용이 적어 보이는 최선의 선택임
- 전역 최적해(Globally Optimal): 문제 전체를 고려했을 때 얻을 수 있는 가장 이상적인 최종 결과값임
- 탐욕적 선택 속성(Greedy Choice Property): 이전의 선택이 이후의 선택에 영향을 주지 않고, 현재의 최선 선택이 모여 전체 최적해를 구성하는 성질임
- 최적 부분 구조(Optimal Substructure): 작은 문제들의 최적 해결 방법이 큰 문제의 최적 해결 방법의 일부가 되는 성질임

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘은 전체적인 최적해를 구하기 위해, 매 단계에서 현재 기준으로 가장 좋아 보이는 국소 최적해를 즉시 확정해 나가는 알고리즘 설계 기법임
- **배경/필요성**: 모든 경우의 수를 탐색하는 완전 탐색이나 복잡한 상태를 관리하는 동적 프로그래밍의 연산 비용이 너무 클 때, 빠른 속도로 정답에 근접한 해를 도출하거나 최적성이 보장되는 문제의 해결 시간을 단축하기 위해 사용됨

## Ⅱ. 특징

- 한 번 내린 결정을 번복하지 않고 다음 단계로 진행하므로 구현이 매우 단순하고 실행 속도가 빠르며, 추가적인 메모리 소모가 적음
- 항상 최적해($Optimal$ $Solution$)를 보장하지는 않으나, 탐욕적 선택 속성과 최적 부분 구조가 증명된 문제에서는 가장 효율적인 정해($Correct$ $Solution$)가 됨
- 정답이 보장되지 않는 복잡한 $NP-Hard$ 문제 등에서는 근사 알고리즘($Approximation$ $Algorithm$)의 기초 논리로 활용되어 실용적인 해를 제공함

## Ⅲ. 종류 및 비교

| 판단 기준 | 탐욕 알고리즘 (Greedy) | 동적 프로그래밍 (DP) | 완전 탐색 (Brute-force) |
|:---|:---|:---|:---|
| **선택 논리** | 현재 시점의 최선만 고집 | 과거의 결과를 참조해 비교 | 모든 가능성을 일일이 대조 |
| **속도/비용** | 매우 빠름 (상수/선형) | 중간 (상태 수 비례) | 매우 느림 (지수/팩토리얼) |
| **정답 보장** | 특정 조건 만족 시에만 보장 | 항상 보장 (점화식 전제) | 항상 보장 (전수 조사) |
| **대표 사례** | 허프만 코딩, 동전 거스름돈 | 배낭 문제, 최단 경로 | 외판원 순회(TSP), 순열 |

> 요약: 성능이 최우선이고 탐욕적 선택의 정당성이 입증되었다면 탐욕법을, 정밀한 최적해가 필요하면 DP를 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 후보 집합 ($Candidate$) | 현재 단계에서 선택 가능한 모든 항목의 모음이며, 선택 시 기준에 따라 정렬되어 있거나 추출됨 |
| 선택 절차 ($Selection$) | 후보 중 현재 가장 가치가 높거나 비용이 낮은 항목을 국소 최적해로 선정하는 규칙임 |
| 타당성 검사 ($Feasibility$) | 선정된 항목이 문제의 제약 조건(예: 무게 제한, 시간 중복 등)을 위반하지 않는지 확인함 |
| 해답 검사 ($Solution$) | 지금까지 선택된 항목들의 집합이 문제의 목표를 달성했는지 확인하고 종료 여부를 결정함 |

```text
[ 탐욕 알고리즘 처리 구조 ]
Input -> {Candidates} -> [Selection Rule] -> [Feasibility Check] -> Result Set
             ^                     | (Iterate)                     |
             +---------------------+-------------------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 데이터 정렬  | --> | 최선 후보 선택 | --> | 제약 조건 검증 | --> | 최종 해 확장 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **데이터 정렬** — 선택 기준(예: 단위 무게당 가격)에 따라 입력 데이터를 미리 오름차순 또는 내림차순으로 정렬함
2. **후보 선택** — 정렬된 목록의 맨 앞에서 현재 가장 유리해 보이는 항목을 하나 추출함
3. **제약 검증** — 추출된 항목을 전체 해에 포함했을 때 문제의 규칙을 어기지 않는지(예: 용량 초과) 확인함
4. **결과 누적** — 검증을 통과하면 해당 항목을 최종 답안 집합에 추가하고, 목표가 달성될 때까지 위 과정을 반복함

## Ⅵ. 실무 적용 및 유의점

1. 탐욕 알고리즘은 직관적으로는 맞아 보이나 실제로는 최적해를 놓치는 경우가 많으므로(예: 거스름돈 문제에서 동전 단위가 배수가 아닐 때), 반드시 교환 논증($Exchange$ $Argument$)이나 반례 테스트를 통해 전역 최적성 도달 여부를 이론적으로 검증해야 함
2. 실무 스케줄링이나 물류 배차 시스템에서 탐욕법을 휴리스틱($Heuristic$)으로 사용할 경우에는, 최적해와의 오차 범위를 측정하고 실행 속도와의 트레이드오프를 평가하여 서비스 수준 합의서($SLA$)를 충족하는지 확인해야 함

## Ⅶ. 결론

- 탐욕 알고리즘은 계산 비용을 최소화하면서 강력한 최적화 성능을 제공하는 설계 기법이며, 설계자는 탐욕적 선택의 정당성을 철저히 분석하여 시스템의 속도와 정확도를 동시에 확보해야 함
