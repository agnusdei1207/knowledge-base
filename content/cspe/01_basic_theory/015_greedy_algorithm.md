## Ⅰ. 개요

- **정의**: 매 단계에서 되돌리지 않는 국소 최적 선택을 반복해 전역 최적해를 구성하는 알고리즘 설계 전략
- **배경/필요성**: 완전탐색은 $O(2^N)$ 이상의 지수 시간이 필요하고 DP는 상태 테이블 저장이 필요하므로, 두 조건(탐욕적 선택 속성·최적 부분 구조)이 성립하는 문제에서는 정렬과 단일 순회만으로 최적해를 얻는 더 경제적인 대안이 필요함
- **출제 의도**: 탐욕법 적용 가능 여부를 수학적으로 검증하는 능력, DP·완전탐색과의 선택 기준을 구분하는 판단력 확인
- **답안 방향**: 성립 조건(탐욕적 선택 속성·최적 부분 구조) 정의 → 정당성 증명 방식(교환 논증) → 실패 사례와 DP 전환 기준으로 전개

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐욕법 적용 가능 여부 판단 | 탐욕적 선택 속성, 최적 부분 구조, 교환 논증 | 조건 검증 없이 탐욕법 적용을 단정 |
| DP·완전탐색과의 선택 기준 | 시간·공간 복잡도 차이, 실패 사례(0/1 배낭·임의 단위 동전) | "탐욕법은 항상 빠르고 정확하다"는 범위 오류 |

> 요약: 이 문제는 탐욕법이 성립하는 구조적 조건과, 그 조건이 깨졌을 때 DP로 전환하는 판단력을 확인하려는 것임.

## Ⅱ. 구조 및 구성요소

```text
후보 집합 -> 탐욕 기준으로 정렬 -> 제약 조건 검사 -> 해 집합에 확정(불가역)
                                        |
                                        +-> 위반 시 건너뜀(해 집합에서 영구 제외)
```

| 구성요소 | 역할 | 비유 |
|:---|:---|:---|
| 탐욕 기준(Greedy Criterion) | 매 단계 "최선"을 판별하는 정렬 키(종료 시각, 단위 가치, 간선 가중치 등) | 가격표를 먼저 확인하는 행위 |
| 후보 집합(Candidate Set) | 선택 가능한 원소 전체 | 진열대에 놓인 물건 전체 |
| 제약 조건 검사(Feasibility Check) | 현재 후보가 해 집합에 포함 가능한지 판정 | 배낭에 남은 무게 확인 |
| 해 집합(Solution Set) | 확정된 선택의 누적, 한 번 추가되면 제거하지 않음 | 이미 담은 물건 |
| 정당성 증명(Exchange Argument) | 탐욕 선택을 다른 선택으로 교체해도 해가 나빠지지 않음을 증명 | "다른 걸 골라도 더 좋아지지 않음"을 미리 확인 |

> 요약: 탐욕 알고리즘은 탐욕 기준으로 정렬한 후보를 제약 조건 검사 후 해 집합에 불가역적으로 추가하는 구조이며, 이 전략의 유효성은 교환 논증으로 별도 증명해야 함.

그래프 최적화에서 크루스칼·프림(012 참조)은 간선 가중치를 탐욕 기준으로 삼아 각각 사이클 검사·최소 간선 확장으로 MST를 구성하는 탐욕적 선택 속성의 대표 사례이며, 세부 동작은 012에서 다룬 내용을 참조함.

## Ⅲ. 동작원리 및 흐름도

```text
입력(후보 목록) -> 탐욕 기준 정렬 -> 순회하며 제약 검사 -> 확정 또는 스킵 -> 해 출력
```

- 1단계 기준 정렬: 문제별 탐욕 기준(활동 종료 시각, 단위 가치, 동전 액면 등)으로 후보를 $O(N \log N)$에 정렬
- 2단계 순회 검사: 정렬 순서대로 현재 후보가 제약을 위반하는지 $O(1) \sim O(\alpha(N))$에 판정
- 3단계 확정: 위반이 없으면 해 집합에 추가하고 이후 다시 검토하지 않음(불가역)
- 4단계 검증: 모든 후보 검토 후, 교환 논증으로 이 선택 순서가 전역 최적임을 확인 — 예: 활동 선택 문제에서 종료 시각이 가장 빠른 활동을 먼저 선택하면 남는 시간이 최대가 되어 이후 선택 가능 폭이 줄지 않음이 증명됨

> 요약: 정렬 $O(N \log N)$ 후 단일 순회 $O(N)$로 해를 확정하며, 이 순서가 최적임은 별도의 교환 논증으로 뒷받침해야 함.

## Ⅳ. 특징

- 효율성: 추가 상태 테이블 없이 정렬 $O(N \log N)$ + 순회 $O(N)$로 해를 구해 DP 대비 공간 사용량이 $O(1) \sim O(N)$으로 작음
- 구현 단순성: 결정을 번복하는 로직이 없어 코드가 간결하고 디버깅 대상이 적음
- 조건 의존성(한계): 탐욕적 선택 속성이 성립하지 않으면 국소 최적 선택이 전역 최적해를 보장하지 못함
- 검증 부담: 적용 전 교환 논증 또는 매트로이드 구조 확인이 필수이며, 이를 생략하면 오답 위험이 있음

## Ⅴ. 심화 비교 및 적용 판단

| 판단 기준 | 탐욕법 성립(활동 선택·표준 화폐 단위) | 탐욕법 실패(0/1 배낭·임의 단위 동전) |
|:---|:---|:---|
| 구조 조건 | 상위 단위가 하위 단위의 배수 관계, 물건 분할 가능 | 물건 분할 불가, 단위 간 배수 관계 붕괴 |
| 대표 사례 | 활동 선택: 종료 시각 순 선택으로 최대 개수 확보. 500·100·50·10원 거스름돈: 큰 단위부터 선택 시 항상 최소 개수 | 0/1 배낭: 무게 10에서 [무게6,가치30] 선택 시 [무게5,가치28]+[무게5,가치27]=55를 담지 못함(탐욕 30 < 최적 55). {1,3,4}원으로 6원 거슬러줄 때 탐욕 4+1+1=3개, 최적 3+3=2개 |
| 판정 근거 | 교환 논증으로 국소 선택이 전역 최적과 일치함을 증명 | 국소 선택이 이후 선택 가능 공간을 왜곡함을 반례로 확인 |
| 대안 | 탐욕법을 그대로 채택 | 상태 테이블 기반 DP로 전환(013 참조) |

> 요약: 탐욕법 채택 여부는 문제가 배수 관계·분할 가능성 같은 매트로이드적 구조를 갖는지에 달려 있으며, 구조가 깨지면 반드시 DP로 전환해야 함.

**리스크·대응**:
- 조건 미검증 채택: 교환 논증을 생략하고 탐욕 기준만으로 적용 → 반례 케이스로 정당성 선검증 (지표: 임의 단위 동전·0/1 배낭류 회귀 테스트 통과율)
- 근사 허용 문제에 정확해 요구: NP-Hard 문제(집합 커버 등)에 탐욕법을 정확해 산출용으로 오적용 → 근사비가 증명된 탐욕 근사 알고리즘으로 전환 (지표: 실측 근사비 대 이론적 상한 $O(\ln N)$ 비교)

**도입 후 점검 지표**:
- 정확성: 반례(임의 단위 동전, 0/1 배낭류) 회귀 테스트 통과 여부
- 성능: 정렬 $O(N \log N)$ 이론치 대비 실제 처리 시간 편차

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 문제의 탐욕적 선택 속성·최적 부분 구조 성립 여부를 교환 논증으로 검증하고 반례 케이스를 확보
2. 중기: 검증이 끝난 영역(OSPF 라우팅의 Dijkstra, 압축의 Huffman, 스케줄링의 활동 선택)에 탐욕 기준을 코드화하고 실패 사례(0/1 배낭·임의 단위 동전)를 회귀 테스트에 포함
3. 장기: 문제 구조(배수 관계·분할 가능성)를 판별하는 체크리스트를 설계 표준으로 정착시키고, NP-Hard 문제는 근사비가 보장된 탐욕 근사 알고리즘으로 적용 범위를 확장

- 기술사적 판단: 문제 구조가 매트로이드적(배수 관계·분할 가능)이면 탐욕법을, 그렇지 않으면 DP 또는 근사 알고리즘을 선택
- 기술사 제언: 실무에서 가장 흔한 오류는 교환 논증 생략이므로, 설계 리뷰 단계에서 반례 검증을 의무화해야 함
- 향후 발전 방향: NP-Hard 문제의 근사비 보장 탐욕 알고리즘, 실시간 입력에 대응하는 온라인 탐욕 알고리즘으로 적용 영역이 확장되는 추세임
