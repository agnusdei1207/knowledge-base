## Ⅰ. 개요
- **정의**: 각 단계에서 지역 최적해를 선택하여 전체 최적해를 구하는 알고리즘 설계 기법
- **배경/필요성**: DP(014 참조)는 모든 하위 문제를 계산하므로 시간·공간 비용이 큼. 탐욕 선택 속성이 성립하는 문제에서는 되돌림 없이 한 번의 순차 선택만으로 최적해를 얻어 연산량을 줄일 수 있음
- **비유**: 뷔페에서 접시 공간이 한정될 때, 남은 공간 대비 만족도가 가장 높은 음식부터 담는 방식과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐욕 기법의 정당성 증명 능력 확인 | 탐욕 선택 속성 + 최적 부분 구조 두 조건 모두 서술 | 모든 문제에 적용 가능하다고 오해하지 말 것. 정당성 증명 없이 적용하면 오답 |

> 요약: 지역 최적 선택의 반복으로 전체 최적을 달성하되, 두 가지 성질이 보장될 때만 정확함

## Ⅱ. 구성요소
```text
문제 입력
   |
   v
+------------------+     +-------------------+
| 탐욕 선택 함수    | --> | 해 집합 갱신       |
+------------------+     +-------------------+
   |                            |
   v                            v
+------------------+     +-------------------+
| 유망성 검사       | --> | 해 완성 여부 판단  |
+------------------+     +-------------------+
                                |
                                v
                          최적해 반환
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 탐욕 선택 함수 | 현재 단계에서 국소 최적 원소를 고르는 기준 함수 | 뷔페에서 '단위 공간당 만족도' 계산기 |
| 유망성 검사 | 선택한 원소를 해 집합에 추가해도 제약 조건을 위반하지 않는지 확인 | 접시에 담아도 넘치지 않는지 확인 |
| 해 집합 | 지금까지 선택한 원소들의 모음 | 접시 위에 올라간 음식 목록 |
| 목적 함수 | 해 집합의 품질을 평가하는 함수 | 담긴 음식의 총 만족도 |
| 탐욕 선택 속성 | 각 단계의 지역 최적이 전체 최적의 일부임을 보장하는 성질 | 매번 최선을 골라도 전체 최선이 되는 보장 |
| 최적 부분 구조 | 부분 문제의 최적해가 전체 최적해를 구성하는 성질 | 부분 경로의 최단이 전체 최단에 포함됨 |

> 요약: 선택 함수·유망성 검사·해 집합·목적 함수가 루프를 이루며, 탐욕 선택 속성과 최적 부분 구조가 정당성을 뒷받침함

## Ⅲ. 절차
```text
후보 집합 정렬 --> 탐욕 선택 --> 유망성 검사 --> 해 집합 갱신
      ^                                              |
      +------------ 후보 소진 또는 해 완성까지 -------+
```
- 1단계: **후보 정렬** — 탐욕 기준(예: 단위 무게당 가치)에 따라 후보 원소를 정렬함
- 2단계: **탐욕 선택** — 정렬 순서대로 가장 유리한 원소를 선택함
- 3단계: **유망성 검사** — 선택 원소가 제약 조건(용량, 시간 등)을 위반하면 건너뜀
- 4단계: **해 집합 갱신 및 종료 판단** — 조건 충족 시 해 집합에 추가하고, 후보가 소진되거나 해가 완성되면 종료함

> 요약: 정렬 → 선택 → 검사 → 갱신의 단일 순회로 해를 구성하므로 되돌림이 없음

## Ⅳ. 문제점
- 정당성 미보장: 탐욕 선택 속성이 성립하지 않는 문제에 적용하면 최적해가 아닌 근사해만 산출됨 — 0/1 배낭 문제에서 탐욕 적용 시 반례 존재
- 증명 부담: 문제마다 탐욕 선택 속성과 최적 부분 구조를 별도로 증명해야 하므로 설계 비용이 높음 — 증명 없이 사용하면 오답 위험
- 해 품질 편차: 근사 적용 시 최적해 대비 품질 격차가 문제 구조에 따라 크게 달라짐 — 근사 비율의 상한을 사전에 분석하기 어려움

> 요약: 적용 가능 범위가 좁고, 정당성 증명 부담이 크며, 근사 적용 시 품질 보장이 어려움

## Ⅴ. 개선방안
1. 단기: 매트로이드(matroid) 구조 확인 절차를 설계 초기에 적용하여 탐욕 적용 가능 여부를 체계적으로 판별함
2. 중기: 탐욕 + DP 하이브리드 설계를 도입하여 탐욕이 실패하는 하위 문제에만 DP를 적용함
3. 장기: 근사 비율 분석 프레임워크를 마련하여 탐욕 근사 적용 시 해 품질 하한을 사전에 보장함

> 요약: 매트로이드 판별 → 하이브리드 설계 → 근사 비율 보장 순으로 적용 범위와 신뢰성을 확대함

## Ⅵ. 전망
- 발전 방향: 온라인 알고리즘, 스트리밍 환경에서 실시간 의사결정에 탐욕 기반 근사가 확대 적용됨
- 기술사적 판단: 분수 배낭, 최소 신장 트리(012 참조), 허프만 코딩(032 참조) 등 고전 문제 외에 스케줄링·네트워크 라우팅에서도 핵심 설계 패턴으로 유지됨
- 기술사 제언: 탐욕 적용 시 정당성 증명 단계를 생략하지 말고, 적용 불가 시 백트래킹(016 참조)이나 DP와 비교 분석하여 적합한 기법을 선택할 것
