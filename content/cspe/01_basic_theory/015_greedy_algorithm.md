# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 미래를 생각하지 않고 '현재 단계에서 당장 가장 좋아 보이는 최적의 선택'만을 연속해서 집어 전체 해답에 도달하는 알고리즘 최적화 기법이다.
- **왜 필요한가**: 모든 경우의 수를 확인(완전 탐색)하기엔 너무 오랜 시간이 걸릴 때, 초고속으로 "조건이 맞으면 완벽한" 또는 "충분히 쓸만한 수준의" 해답을 내놓기 위함이다.
- **핵심 직관**: 마시멜로 이야기의 정반대다. 나중의 더 큰 보상을 기다리며 복잡하게 계산하지 않고, 지금 당장 집을 수 있는 가장 큰 마시멜로부터 무조건 챙겨 나간다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 국소 최적해 (Local Optimum) | 지금 처한 그 한순간에 내린 가장 좋고 이기적인 결정 | 당장 눈앞에 떨어져 있는 500원짜리 동전 줍기 |
| 전역 최적해 (Global Optimum) | 전체 과정을 모두 끝냈을 때 도달하는 최종적인 가장 좋은 해답 | 게임 전체를 통틀어 가장 높은 최종 점수 획득 |
| 매트로이드 (Matroid) | 그리디 알고리즘이 무조건 전역 최적해를 찾는다고 보장해 주는 수학적 구조 | 동전 단위가 무조건 서로 배수 관계인 안전한 환전 시스템 |

## 깊이 이해
- **배경·문제의식**: 거스름돈을 줄 때 굳이 캐싱(DP)을 쓰면 코드가 무겁다. "단순히 당장 큰 단위 동전부터 주면 안 될까?"라는 극강의 실용적이고 빠른 접근이다.
- **작동 원리**: 탐욕적 선택 조건(현재 선택이 미래에 악영향을 주지 않음)과 최적 부분 구조가 전제되어야 100% 정답을 맞힌다.
  - 당장 가장 좋아 보이는 해를 고른다 (우선순위 선택)
  - 고른 해가 규칙 위반이 아닌지 본다 (적절성 검사)
  - 목표가 달성되었는지 확인하고 아니면 반복한다 (해답 검사)
- **비유**: 내비게이션 없이 운전할 때, 교차로가 나올 때마다 무조건 '지금 당장 정체가 없는 길'로만 꺾어서 결국 목적지에 빨리 닿으려는 운전자다.
- **구체 예시**: 한국 거스름돈(500, 100, 50, 10)은 서로 배수 관계(매트로이드)이므로 무조건 500원부터 많이 집으면 동전 개수가 최소가 된다(탐욕법 성공). 반면 동전이 500, 400, 100일 때 800원을 주려면, 탐욕법은 500(1)-100(3) 4개를 내놓지만 실제 정답은 400(2) 2개다(탐욕법 오답).
- **흔한 오해·주의점**: 탐욕법은 "대충 찍는 법"이 아니다. 크루스칼, 다익스트라, 허프만 코딩 같은 명작 알고리즘들은 "탐욕법으로 풀어도 무조건 100% 정답이 나온다"는 증명 위에 세워진 치밀한 로직이다.

## 연결 개념
- (012 최소 신장 트리 참조) 탐욕적 선택이 항상 정답이 되는 인프라 설계 알고리즘
- 근사 알고리즘 (탐욕법으로 100% 정답을 못 구해도 90점 수준으로 타협해서 구하는 실용 기법)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 매 선택의 순간에 국소적인 최적해를 도출하여, 최종적인 전역 최적해에 빠르게 도달하려는 발견적 휴리스틱 기법.
> 2. **가치**: O(N log N) 등 매우 빠른 다항 시간 내에 최적해를 구하거나, 해결 불가한 NP-Hard 문제의 훌륭한 근사해 도출 방안 확보.
> 3. **판단 포인트**: 수학적으로 매트로이드(Matroid) 구조가 성립하는지 사전 증명해야만 치명적 오답(로컬 옵티멈 함정) 도출 리스크를 막는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐욕법의 100% 정당성 증명 역량 | 탐욕적 선택 속성, 최적 부분 구조 2대 조건 | 장점만 나열하고 "항상 최적해를 보장하진 않음" 누락 |
| 실무 활용 방안 및 타 패러다임 비교 | 다익스트라, 크루스칼, 허프만 매핑 도출 | DP와의 비교 시 하위 문제 종속성 판단 기준 부재 |

> 요약: 당장의 이기적 선택이 전체 최적으로 이어지는 조건(정당성)을 명시하고, DP로 풀어야 할 겹치는 문제와의 구별 능력을 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 미래 상태 변화를 고려하지 않고 오직 현재 직면한 단계에서의 최선(Local Optimum)을 반복 선택하여 전체 해(Global Optimum)를 구하는 최적화 기법
- 배경: 지수 시간(O(2^n))이 걸리는 조합 탐색 문제를 제한된 실시간 컴퓨팅 자원 내에서 현실적인 허용 시간 내에 해결 요구 급증
- 필요성: 네트워크 최적 라우팅 갱신, 데이터 파일 압축 등에서 O(N log N) 고속 처리 아키텍처 필수 도입 요건 발생

---

## Ⅱ. 구조 및 구성요소

```text
[입력 데이터 정렬] -> [탐욕적 해 선택] -> [제약 적절성 검사] -> [통과 시 해답 집합 누적] -> 완료 검사
                          |                       |                     |
                          +--------<반복>---------+---------------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 해 선택 (Selection) | 남은 선택지 중 현재 기준 가장 가치 높은 요소를 탐욕적으로 추출 | 우선순위 큐나 사전 정렬(Sorting) 기법 필수 동반 |
| 적절성 검사 (Feasibility) | 추출된 선택지가 문제의 용량 제약 등 정해진 규칙을 위배하는지 판단 | 위배 시 해당 요소를 영구 폐기하고 즉시 다음 순위 선택 |
| 해답 검사 (Solution) | 현재까지 누적된 해답 집합이 최종 도달 목표를 충족했는지 종료 검사 | 종료 미달 시 다시 상단 해 선택(Selection) 단계로 반복 |

> 요약: 탐욕 알고리즘은 '정렬된 대기열에서 1등 뽑기 → 제약조건 통과 여부 확인 → 누적'의 3단계를 단순 루프화한 초고속 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
탐욕적 성질 증명 -> 입력값 우선순위 정렬 -> 최적 원소 추출 -> 임시 결과 제약 검증 -> 최종 결과 리턴
```

- 1단계 [사전 증명 및 정렬]: 문제 구조가 탐욕적 선택 속성을 만족하는지 검증 후, 비용/가치 기준 오름차순/내림차순 정렬
- 2단계 [가장 유리한 값 추출]: 정렬된 대기열의 최상위 원소(당장 가장 큰 이득을 주는 값)를 선택 집합 대기열에 편입
- 3단계 [한계 및 제약 검증]: 추출된 원소가 수용 용량 초과나 사이클 형성 등 기존 제약을 위반하면 편입 롤백(완전 버림)
- 4단계 [종료 판단 및 반복]: 목적지 도달 또는 수용 용량 100% 달성 시 멈추고, 그렇지 않으면 2단계 추출로 재진행

> 요약: 미래 변수 추적이나 메모리 할당(DP) 없이, 정렬된 순서에 맞춘 즉각적인 순차 판단과 제약 확인만으로 진행을 확정한다.

---

## Ⅳ. 특징
- 고속 연산 스루풋: 상태를 재귀적으로 깊게 추적하거나 별도 테이블에 캐싱(DP)을 하지 않으므로 시공간 복잡도 성능 극대화
- 전역 최적해 미보장: 문제 구조가 매트로이드를 만족하지 않으면 치명적 오답 산출 (예: 단위가 배수 관계가 아닌 동전 체계)
- 근사 최적화 차선책: NP-Hard 영역의 풀이 불가 문제에서는 100% 정답을 포기하더라도, 90% 근사해를 실용적인 시간에 얻기 위한 전략으로 변환 채택

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 탐욕 알고리즘 (Greedy) | 동적 프로그래밍 (DP) | 선택 기준 |
|:---|:---|:---|:---|
| 선택의 영향 방향 | 현재의 결정이 미래에 롤백 등 영향을 주지 않음 | 앞선 하위 상태의 결과가 미래 결정에 직접 종속됨 | 하위 문제 종속 여부 |
| 상태 저장 메모리 | 불필요 (변수만 쓰는 O(1) 공간 사용) | Memoization 배열 유지 필수 (공간 트레이드오프) | 가용 메모리 제약 한도 |
| 도출 값 정밀도 | 성립 조건 위배 시 오답(국소 최적해 함정) | 조건 관계없이 항상 100% 최적해(전역 최적해) 보장 | 결과 도출 신뢰성 허용치 |

> 요약: 정당성 증명이 100% 끝난 안전 구조이거나, 정답의 90% 수준 근사해로 타협이 가능한 긴급 환경이라면 DP 대신 탐욕 알고리즘을 쓴다.

**리스크·대응:**
- Local Optimum 함정 낙오: 초기 이기적 선택이 향후 최적 경로를 완전히 차단해 오답 산출 → 적용 전 반례(Counter Example) 유닛 테스트 및 수학적 매트로이드 정당성 검토 의무화
- 입력 정렬 연산 병목: 매번 최댓값을 무식하게 찾을 시 루프 순환 전체 O(N^2) 부하 발생 → 우선순위 큐(Min/Max Heap) 자료구조 적용으로 매 추출 연산을 O(log N)으로 강력히 통제

**도입 후 점검 지표:**
- 정확도/근사치 한계선: 탐욕 알고리즘 도출 값이, 완전탐색(백트래킹) 도출 절대 최적해 대비 오차율(Approximation Ratio) 2.0배수를 초과하지 않는지 프로파일링
- 수행 속도 지연: O(N log N) 복잡도 기준, 대용량 100만 건 트랜잭션의 정렬 및 선택 1초 이내 완료 SLA 준수 확인

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 네트워크 OSPF 다이내믹 라우팅: OSPF 공유 라우터 내부에 다익스트라(Greedy) 알고리즘을 이식하여, 장애 단절 발생 시 우회 경로를 실시간 O(E log V)에 재계산
2. 대용량 텍스트/미디어 파일 압축: 파일 내 문자 빈도수를 전수 조사해 가장 출현 빈도가 높은 문자에 극단적으로 짧은 비트를 부여하는 허프만 코딩(Huffman Coding) 압축 모듈 구축
3. 클라우드 작업 스케줄링 선점 최적화: 가장 종료 예상 시간이 빠른 작업(SJF)부터 탐욕적으로 CPU 코어 자원을 우선 할당하여, 단위 시간 내 클러스터 전체 최대 Throughput 처리량 확보

**결론:**
- 기술사 판단: 탐욕 알고리즘 설계는 직관적이고 빠르지만, 예외 반례 하나로 시스템 신뢰성 근간이 붕괴될 수 있으므로 알고리즘 자체보다 적용 전 설계 단계에서의 수학적 매트로이드 증명이 핵심이다.
- 향후 방향: 최근 AI 강화학습 환경에서는 완전한 탐욕(Greedy)이 지역 최적해에 갇히는 현상을 막기 위해, 일정 확률로 완전 임의 탐색을 강제 허용하는 엡실론 그리디(Epsilon-Greedy) 메커니즘으로 융합 진화 중이다.
