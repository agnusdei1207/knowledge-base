## 미리 알고가기

- 국소 최적해: 현재 단계의 기준에서 가장 유리한 선택임
- 전역 최적해: 전체 문제를 고려한 최종 최적 결과임
- 탐욕적 선택 속성: 현재 선택을 포함하는 전역 최적해가 존재하는 성질임
- 최적 부분 구조: 부분 문제의 최적해가 전체 최적해 구성에 쓰이는 성질임
- 교환 논증: 선택을 바꿔도 더 나빠지지 않음을 보여 탐욕 선택의 정당성을 증명하는 방식임

## 작성 근거(검토용)

- **개요 구성**: 탐욕법의 핵심은 현재 선택 확정과 되돌림 없음이므로 정의에 직접 배치함
- **Ⅱ. 특징 선정**: 상태 비용·후보 관리 비용·최적성 증명·휴리스틱 통제는 탐욕법의 장단점을 가르는 요소임
- **Ⅲ 비교축 선정**: 선택 방식, 처리 범위, 최적성 근거가 탐욕법과 대안의 차이를 가름
- **Ⅳ 구조 선정**: 후보, 선택 규칙, 타당성, 부분해, 남은 문제는 탐욕 반복의 필수 상태라 남김
- 반례 검증과 해 품질 차이는 탐욕법을 정확 알고리즘과 휴리스틱으로 구분하는 기준임

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘은 매 단계에서 현재 기준의 최선 후보를 선택하고 이전 선택을 되돌리지 않는 설계 기법임
- **배경/필요성**: 탐색·상태 저장 비용을 줄이기 위해 현재 단계의 선택 기준과 전역 최적해 보장 여부를 검증해야 함

## Ⅱ. 특징

- 선택을 확정한 뒤 되돌림 상태를 저장하지 않음
- 후보 정렬·힙·방문 집합 같은 선택 비용은 별도로 발생함
- 탐욕적 선택 속성이 증명되면 전역 최적해가 보장됨
- 증명이 없으면 반례와 해 품질 지표로 휴리스틱 여부를 판단함

## Ⅲ. 종류 및 비교

| 판단 기준 | 탐욕 알고리즘 (Greedy) | 동적 계획법 (DP) | 완전 탐색 (Brute-force) |
|:---|:---|:---|:---|
| 선택 방식 | 현재 최선 후보를 즉시 확정 | 상태별 최적값을 저장해 전이 비교 | 모든 후보의 목적값 비교 |
| 탐색 범위 | 현재 선택으로 확정한 한 경로 | 정의한 상태 공간 | 전체 후보 공간 |
| 최적성 근거 | 탐욕적 선택 속성 증명 | 점화식의 최적성 증명 | 전수 비교 결과 |

> 요약: 현재 선택이 전역 최적해에 포함됨을 증명하면 탐욕법을, 부분 문제 결과를 비교·재사용하면 DP를, 모든 후보 확인이 필요하면 완전 탐색을 적용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 후보 집합 | 현재 단계의 선택 대상 |
| 선택 규칙 | 국소 최적 후보의 판정 기준 |
| 타당성 검사 | 선택 후보의 제약 위반 판정 |
| 부분해 | 채택한 선택의 누적 결과 |
| 남은 문제 | 선택 결과를 반영한 다음 상태 |

```text
[ 탐욕 구조 ]
후보 -> 최선 선택 -> 타당한가? -> 채택 -> 남은 문제 갱신
                                |
                                v
                               제외
```

> 요약: 탐욕 알고리즘은 선택 규칙으로 후보를 고르고 타당한 선택을 부분해에 누적해 남은 문제를 갱신함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------------+     +----------------+     +----------------+     +----------------+
| 선택 기준 정의 | --> | 후보 우선순위화 | --> | 타당성 검사    | --> | 부분해 갱신   |
+----------------+     +----------------+     +----------------+     +----------------+
```

1. **선택 기준 정의**: 비교할 비용·이익·거리 기준을 정함
2. **후보 우선순위화**: 정렬·힙·순차 확인으로 후보를 관리함
3. **타당성 검사**: 선택 후보가 문제 제약을 위반하는지 확인함
4. **부분해 갱신**: 통과한 후보를 확정하고 같은 선택 규칙을 반복할 수 있도록 남은 문제를 다시 정의함

> 요약: 탐욕법은 후보를 고르는 기준뿐 아니라 선택 후 남은 문제가 같은 구조로 유지되는지까지 확인해야 함.

## Ⅵ. 실무 사례

1. 거스름돈 알고리즘은 작은 반례와 교환 논증으로 탐욕 선택의 최적해 보장 여부를 확인함
2. 작업 스케줄링은 탐욕 휴리스틱을 적용하고 제약 위반률·최적해 대비 차이를 확인함

## Ⅶ. 결론

- 탐욕 알고리즘은 선택 속성이 증명되면 정확 알고리즘으로, 증명하기 어렵다면 반례와 품질 지표로 통제하는 휴리스틱으로 써야 함
