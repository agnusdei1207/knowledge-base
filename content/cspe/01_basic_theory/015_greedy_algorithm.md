# 015. 탐욕 알고리즘 (Greedy Algorithm)

## 미리 알고가기

- **탐욕적 선택 속성 (Greedy Choice Property)**: 앞선 선택이 이후의 선택에 영향을 주지 않으며, 매 단계의 최선이 전체의 최선으로 이어지는 성질임
- **최적 부분 구조 (Optimal Substructure)**: 부분 문제들의 최적해를 결합하면 전체 문제의 최적해가 되는 성질임
- **근사 알고리즘 (Approximation Algorithm)**: 최적해를 구하기 어려운 문제(NP-hard 등)에서 탐욕법을 통해 실무적으로 수용 가능한 수준의 답을 도출함

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘(Greedy Algorithm)은 문제를 여러 단계로 나누어 해결할 때, 매 순간 가장 이익이 크거나 비용이 적은 선택(Local Optimal)을 반복하여 최종 해답을 도출하는 설계 기법임
- **배경/필요성**: 모든 경우의 수를 따지는 완전 탐색이나 표를 채우는 DP는 대규모 데이터에서 연산 비용이 높음. 특정 조건을 만족하는 문제에 대해 연산량을 획기적으로 줄여 실시간 처리를 가능케 하고, 최적해를 보장하지 못하는 경우에도 빠른 근사치를 제공하기 위해 사용함

## Ⅱ. 특징 및 비교

탐욕법은 '한 번의 선택을 번복하지 않는다'는 점에서 DP와 근본적으로 차이가 있으며, 정답 보장 여부가 문제 구조에 강하게 종속됨.

| 비교 항목 | 탐욕 알고리즘 (Greedy) | 동적 계획법 (DP) | 완전 탐색 (Brute-force) |
|:---|:---|:---|:---|
| **결정 방식** | **매 단계 최선 하나를 확정** | 여러 후보를 비교하여 선택 | 모든 경우를 조사 |
| **속도/비용** | **매우 빠름 ($O(n \log n)$ 이하)** | 상대적으로 느림 (상태 수 비례) | 매우 느림 (지수 시간) |
| **정답 보장** | 탐욕 속성 성립 시에만 보장 | **항상 보장** | 항상 보장 |
| **주요 특징** | 상향식 접근, 되돌림 없음 | 하향/상향 혼용, 결과 저장 | 전수 조사 |
| **대표 사례** | 동전 교환(표준), 허프만, MST | 배낭 문제(DP), 최단 경로 | 순열, 조합 생성 |

> 요약: 보장된 정답이 필요하면 DP, 속도가 생명이고 탐욕 속성이 증명되었다면 탐욕법이 최적임.

## Ⅲ. 구성요소/구조

탐욕 알고리즘은 후보군 중에서 기준에 맞는 최선을 선택하고, 그것이 문제의 제약 조건을 지키는지 검증하며 해를 완성해 나감.

- **구성요소**:
  - **후보 집합 (Candidate Set)**: 선택 가능한 해의 구성 원소들
  - **선택 절차 (Selection Procedure)**: 현재 상태에서 가장 좋은 후보를 고르는 기준
  - **적합성 검사 (Feasibility Check)**: 선택한 후보가 문제의 제약 조건을 위반하지 않는지 확인
  - **해 검사 (Solution Check)**: 완성된 해가 문제의 요구사항을 충족하는지 검증

- **처리 프로세스 (원리/흐름도)**:

```text
[Greedy Step]
1. 정렬/우선순위화 (후보군 준비)
2. 가장 좋은 후보 1개 선택 (Greedy Choice)
3. if (제약 조건 통과):
     - 해 집합에 추가
   else:
     - 해당 후보 제외
4. 문제 해결 시까지 반복
```

1. **선택**: 종료 시간이 가장 빠르거나 가중치가 가장 작은 것 등 '기준'에 맞춰 선택함
2. **확정**: 한 번 선택된 요소는 이후 단계에서 다른 대안이 나오더라도 바뀌지 않음
3. **누적**: 단계별 최적해들이 모여 전체 문제의 최종 결과가 됨

## Ⅳ. 문제점 및 개선방안

1. **국소 최적해(Local Optimum)의 함정**: 매 순간의 최선이 장기적으로는 손해가 되어 전체 최적해(Global Optimum)를 놓칠 수 있음 (예: 거스름돈 동전이 500, 400, 100원일 때 800원 거슬러주기)
   - **개선방안**: 탐욕적 선택이 항상 최적임을 **교환 논증(Exchange Argument)** 등을 통해 증명하거나, 증명이 안 될 경우 DP로 설계 변경을 검토함 (확인: 반례 데이터 존재 여부)

2. **근사해의 품질 보장 불확실**: NP-hard 문제(집합 커버 등)에서 탐욕법을 쓸 경우, 도출된 해가 최적해와 얼마나 차이 나는지 알기 어려움
   - **개선방안**: 해당 문제의 **근사비(Approximation Ratio)**를 분석하여 최악의 경우에도 허용 가능한 오차 범위 내에 있는지 사전 검증함 (확인: 최악의 오차율 상한)

3. **데이터 정렬 오버헤드**: 탐욕적 선택을 위해 매번 데이터를 정렬하거나 검색해야 하는 비용이 발생함
   - **개선방안**: 우선순위 큐(Priority Queue)를 활용하여 정렬된 상태를 유지하면서 최적 후보를 $O(\log n)$에 추출하도록 구현함 (확인: 힙 구조 활용을 통한 성능 개선)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터 압축 (Huffman) | 출현 빈도가 낮은 문자부터 탐욕적으로 결합하여 이진 트리를 구성하고 가변 길이 코드 할당 | 압축률, 평균 비트 수 |
| 네트워크 인프라 (MST) | 최소 비용으로 모든 지점을 잇기 위해 가장 저렴한 간선부터 선택 (Kruskal, Prim) | 총 공사 비용, 연결 안정성 |
| 작업 스케줄링 (Task) | 종료 시간이 가장 빠른 작업부터 배정하여 하나의 자원에서 처리 가능한 최대 작업 수 확보 | 자원 이용률, 처리 작업 수 |
| 동영상 스트리밍 (ABR) | 네트워크 대역폭 변화에 따라 매 순간 최적의 화질 조각을 선택하여 재생 끊김 방지 | 버퍼링 횟수, 평균 재생 화질 |

> 요약: 정답의 '정확성'보다 '속도'와 '자원 효율'이 중요한 실시간 결정 시스템에서 핵심적으로 사용됨.

## Ⅵ. 결론

탐욕 알고리즘은 복잡한 문제의 해답을 '가장 단순한 선택의 연쇄'로 풀어내는 강력한 설계 전략임. 기술사는 탐욕법이 제공하는 속도의 이점을 취하면서도, 그것이 가져올 수 있는 오답의 위험을 수학적으로 입증하거나 제어할 수 있는 역량을 갖추어야 함.

특히 인공지능 탐색이나 복잡한 자원 배분 문제에서는 탐욕법을 기초로 하되, 가끔은 좋지 않은 선택도 허용하는 Simulated Annealing이나 대안을 함께 고려하는 Beam Search 등과 결합하여 해의 품질을 높이는 유연한 사고가 필요함. 결국 탐욕은 최적을 향한 '직관'을 알고리즘화한 것이며, 그 직관의 타당성을 검증하는 것이 설계의 핵심임.
