## 미리 알고가기

- 국소 최적해(Locally Optimal): 현재 시점에서 가장 이익이 크거나 비용이 적어 보이는 최선의 선택임
- 전역 최적해(Globally Optimal): 문제 전체를 고려했을 때 얻을 수 있는 가장 이상적인 최종 결과값임
- 탐욕적 선택 속성(Greedy Choice Property): 현재 선택을 포함하는 전역 최적해가 존재하고, 남은 문제가 같은 형태의 하위 문제로 축소되는 성질임
- 최적 부분 구조(Optimal Substructure): 작은 문제들의 최적 해결 방법이 큰 문제의 최적 해결 방법의 일부가 되는 성질임

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘은 매 단계에서 현재 기준으로 가장 유리한 후보를 선택하고 되돌리지 않는 설계 방식이며, 탐욕적 선택 속성이 증명되면 전역 최적해를 보장하고 그렇지 않으면 휴리스틱이나 근사로 사용됨
- **배경/필요성**: 모든 후보를 탐색하거나 상태 전체를 저장하기 어려운 문제에서는 선택 기준을 단순화해 계산 비용을 줄이되, 그 선택이 최적성을 보장하는지 또는 어느 정도의 해 품질을 내는지 검증해야 함

## Ⅱ. 특징

- 선택을 확정한 뒤 이전 상태를 다시 비교하지 않으므로 상태 테이블 유지 비용은 작을 수 있지만, 정렬·힙·방문 집합 같은 후보 관리 비용은 문제별로 포함됨
- 탐욕적 선택 속성과 최적 부분 구조가 증명된 문제에서는 정확한 전역 최적해를 구할 수 있으며, 증명이 없으면 반례로 쉽게 실패할 수 있음
- 복잡한 최적화 문제에서는 근사비가 증명되면 근사 알고리즘으로, 보장이 없으면 휴리스틱으로 사용하고 해 품질을 별도 지표로 관리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 탐욕 알고리즘 (Greedy) | 동적 프로그래밍 (DP) | 완전 탐색 (Brute-force) |
|:---|:---|:---|:---|
| **선택 논리** | 현재 기준 후보를 선택 후 확정 | 상태 전이를 비교하고 저장 | 모든 후보를 열거해 비교 |
| **비용 구조** | 정렬·힙 등 후보 관리 비용 중심 | 상태 수와 전이 비용 중심 | 후보 수 증가에 비례 |
| **정답 보장** | 탐욕적 선택 속성 증명 시 보장 | 점화식과 상태 정의가 맞으면 보장 | 유한 후보를 모두 보면 보장 |
| **대표 사례** | 허프만 코딩, 다익스트라, 프림 | 배낭 문제, 플로이드-워셜 | 외판원 순회(TSP) 완전 탐색, 순열 |

> 요약: 탐욕적 선택의 정당성을 증명할 수 있으면 탐욕법을 쓰고, 되돌림이 필요하거나 상태 의존성이 크면 DP나 완전 탐색으로 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 후보 집합 (Candidate) | 현재 단계에서 선택 가능한 항목 모음이며, 선택 규칙을 적용하기 위해 정렬, 힙, 스캔 방식으로 관리됨 |
| 선택 규칙 (Selection Rule) | 후보 중 현재 목적 함수에 가장 유리한 항목을 고르는 기준임 |
| 타당성 검사 (Feasibility) | 선택 후보가 용량, 시간, 연결성 같은 문제 제약을 위반하지 않는지 확인하는 절차임 |
| 부분해/남은 문제 | 채택된 후보로 부분해를 갱신하고, 선택 이후 남은 후보와 제약 상태를 다시 정의하는 구조임 |

```text
[ 탐욕 알고리즘 처리 구조 ]
Candidate -> Select -> Feasible? -> Accept/Reject -> Update Remaining
     ^                                                        |
     +-------------------------- Done? -----------------------+
```

> 요약: 선택 규칙, 타당성 검사, 부분해 갱신이 맞물려야 탐욕 선택의 정당성과 실행 비용을 판단할 수 있음.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------------+     +----------------+     +----------------+     +----------------+
| 선택 기준 정의 | --> | 후보 우선순위화 | --> | 타당성 검사    | --> | 부분해 갱신   |
+----------------+     +----------------+     +----------------+     +----------------+
```

1. **선택 기준 정의** — 비용, 이익, 거리, 빈도처럼 현재 단계에서 비교할 목적 함수를 정함
2. **후보 우선순위화** — 정렬, 우선순위 큐, 선형 스캔 중 문제에 맞는 방식으로 후보를 관리함
3. **타당성 검사** — 선택 후보를 부분해에 포함했을 때 제약을 위반하는지 확인함
4. **부분해 갱신** — 통과한 후보를 확정하고 남은 후보와 제약 상태를 갱신한 뒤 종료 조건까지 반복함

> 요약: 탐욕법은 후보를 고르는 기준뿐 아니라 선택 후 남은 문제가 같은 구조로 유지되는지까지 확인해야 함.

## Ⅵ. 실무 적용 및 유의점

1. 거스름돈 문제에서 동전 체계가 canonical coin system이 아니면 탐욕 선택이 실패할 수 있으므로, 1·3·4 단위에서 6을 만들 때 탐욕 결과 4+1+1보다 3+3이 낫다는 반례처럼 작은 입력 검증과 교환 논증으로 전역 최적해 보장 여부를 확인해야 함
2. 스케줄링이나 물류 배차에서 탐욕법을 휴리스틱으로 쓰면 하한값, 완화 문제, 소규모 exact solver, 벤치마크 대비 gap, 제약 위반률, 계산 시간으로 해 품질과 실행 비용을 함께 확인해야 함

## Ⅶ. 결론

- 탐욕 알고리즘은 탐욕적 선택 속성을 증명할 수 있는 문제에서는 상태 관리 비용을 줄이는 정확 알고리즘이지만, 증명하기 어려운 문제에서는 반례와 품질 지표로 통제하는 휴리스틱으로 선택해야 함
