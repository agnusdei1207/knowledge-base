## 미리 알고가기

- 국소 최적: 현재 단계에서 가장 좋아 보이는 선택임
- 전역 최적: 전체 문제 관점에서 가장 좋은 최종 해임
- 탐욕 선택 속성: 국소 최적 선택을 포함하는 전역 최적해가 존재한다는 성질임
- 최적 부분 구조: 부분 문제의 최적해가 전체 최적해를 구성하는 성질임
- 교환 논증: 다른 최적해를 탐욕 선택을 포함하도록 바꿔도 손해가 없음을 보이는 증명 방식임

## Ⅰ. 개요

- **정의**: 탐욕 알고리즘은 매 단계에서 현재 기준으로 가장 유리한 선택을 확정하고 되돌리지 않으면서 전체 해를 구성하는 알고리즘 설계 기법임. 탐욕 선택 속성과 최적 부분 구조가 성립하는 문제에서 동적 프로그래밍이나 완전탐색보다 낮은 비용으로 최적해 또는 보장된 근사해를 얻기 위해 사용함.
- **배경/필요성**: 탐욕 알고리즘은 빠르고 구현이 단순하지만, 국소 선택이 항상 전역 최적을 보장하지는 않음. 따라서 정렬 기준, 우선순위, 선택 증명이 없는 탐욕 적용은 오답이 될 수 있음.
- **비유**: 매 순간 가장 싼 연결선을 고르되, 그 선택이 전체 공사비 최소에 포함될 수 있다는 규칙이 증명된 경우에만 믿고 진행하는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘 설계 선택 기준 확인 | 국소 선택, 전역 최적, 탐욕 선택 속성, 증명 | 빠른 알고리즘으로만 설명 |

> 요약: 탐욕 알고리즘은 국소 선택을 확정해 해를 만들며, 그 선택이 전역 최적을 보장한다는 근거가 있어야 함.

## Ⅱ. 특징/비교

| 판단 기준 | 탐욕 알고리즘 | 동적 프로그래밍 | 완전탐색 |
|:---|:---|:---|:---|
| 선택 방식 | 현재 최선 선택을 확정 | 여러 상태의 최적값 비교 | 모든 후보를 탐색 |
| 되돌림 | 일반적으로 없음 | 상태 전이에 따라 간접 비교 | 백트래킹 가능 |
| 적용 조건 | 탐욕 선택 속성 필요 | 중복 부분 문제와 최적 부분 구조 필요 | 입력이 작거나 검증용 |
| 비용 특성 | 정렬·우선순위 큐 중심으로 낮음 | 상태 수와 전이 수에 비례 | 지수적 증가 가능 |
| 선택 기준 | 증명 가능한 빠른 최적화 | 국소 선택이 불충분할 때 | 정확성 검증 또는 작은 입력 |

> 요약: 탐욕은 빠르지만 적용 조건이 엄격하며, 국소 선택의 안전성이 증명될 때 DP보다 단순한 해법이 됨.

- MST의 크루스칼·프림, 다익스트라, 허프만 코딩은 탐욕 선택이 증명되는 대표 사례임
- 배낭 문제처럼 0/1 선택 제약이 있는 경우 단순 가치 비율 탐욕은 최적해를 보장하지 않음
- 근사 알고리즘에서는 최적해가 아니더라도 성능 보장 비율을 제시하면 탐욕 전략이 의미를 가짐

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 후보집합 | ---> | 선택기준 | ---> | 선택확정 |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 제약조건 |      | 검증논리 |      | 최종해   |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 후보 집합 | 매 단계에서 선택 가능한 원소나 행동의 목록임 | 구매 후보 목록 |
| 선택 기준 | 최소 비용, 최대 이익, 가장 이른 종료처럼 후보 우선순위를 정하는 규칙임 | 가격표 정렬 기준 |
| 제약 조건 | 선택이 문제의 유효한 해를 유지하는지 판단하는 조건임 | 예산과 규격 |
| 확정 연산 | 선택한 후보를 해에 포함하고 이후 선택에서 되돌리지 않음 | 계약 체결 |
| 정당성 근거 | 탐욕 선택이 전역 최적에 포함될 수 있음을 설명하는 증명임 | 계약 승인 근거 |

> 요약: 탐욕 알고리즘은 후보를 선택 기준으로 정렬하거나 우선순위화하고, 제약을 만족하는 선택을 확정해 해를 구성함.

- 선택 기준이 문제 목표와 직접 연결되지 않으면 빠르게 틀린 해를 만들 수 있음
- 제약 조건은 사이클 방지, 용량 제한, 마감 시간처럼 문제마다 다르게 구현됨
- 정당성 근거는 컷 속성, 교환 논증, 귀납 증명 등으로 제시할 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 요구확인 | ---> | 후보정렬 | ---> | 선택검증 | ---> | 해완성   |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 성질판단 |      | 우선순위 |      | 제약확인 |      | 증명/비용|
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 최적화 목표와 제약 조건을 정의하고 탐욕 선택 속성이 기대되는지 확인함
2. **선택 기준 설계** - 후보를 어떤 기준으로 고를지 정렬 키나 우선순위 큐 기준을 설정함
3. **선택과 검증 반복** - 가장 유리한 후보를 선택하되 제약을 위반하면 제외하고 다음 후보를 검토함
4. **출력/정당성 확인** - 완성된 해의 비용과 제약 만족 여부를 확인하고 탐욕 선택의 정당성을 제시함

> 요약: 탐욕 절차는 선택 기준을 세우고 후보를 빠르게 확정하되, 그 기준이 최적성을 보장하는지 검증하는 흐름임.

- 정렬 기반 탐욕은 정렬 비용 `O(n log n)`이 전체 복잡도를 지배하는 경우가 많음
- 우선순위 큐 기반 탐욕은 후보가 동적으로 변하는 문제에 적합함
- 탐욕이 최적을 보장하지 않으면 반례를 통해 DP나 백트래킹으로 전환해야 함

## Ⅴ. 문제점

- **P1 국소 최적의 함정**: 현재 가장 좋은 선택이 이후 선택 가능성을 줄여 전역 최적을 놓칠 수 있음
- **P2 선택 기준 오정의**: 정렬 키나 우선순위가 목표 함수와 맞지 않으면 일관되게 잘못된 해를 생성함
- **P3 정당성 증명 부족**: 탐욕 선택 속성을 보이지 못하면 알고리즘의 빠른 수행시간만으로 정확성을 주장할 수 없음

> 요약: 탐욕 알고리즘의 위험은 빠른 선택 자체가 아니라 그 선택이 전체 최적을 보장한다는 근거가 약할 때 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 작은 입력의 완전탐색 결과와 비교하고 반례가 발견되면 DP, 백트래킹, 분기한정으로 전환함 (확인: 반례 테스트셋)
- **P2 대응**: 목표 함수와 선택 기준의 관계를 교환 논증이나 컷 속성으로 검증함 (확인: 선택 기준별 결과 비교)
- **P3 대응**: 답안과 설계 문서에 탐욕 선택 속성, 최적 부분 구조, 근사 보장 여부를 명시함 (확인: 정당성 체크리스트)

> 요약: 탐욕 개선은 빠른 구현보다 선택 기준의 증명과 반례 검증을 우선하는 방식이 필요함.

## Ⅶ. 전망

- **향후 발전 방향**: 대규모 최적화와 실시간 의사결정에서는 정확 최적해보다 빠른 근사해가 중요해져 탐욕 기반 근사 알고리즘의 활용이 커짐
- **기술사적 판단**: 탐욕은 성능이 좋은 기법이 아니라 적용 성질이 맞을 때만 정확한 기법임을 분명히 해야 함
- **기술사 제언**: 답안에서는 대표 사례를 나열하기보다 선택 기준, 제약 검증, 정당성 근거를 한 흐름으로 제시해야 함

> 요약: 탐욕 알고리즘은 증명 가능한 선택 기준이 있을 때 강력하며, 정확성 근거가 답안의 핵심임.
