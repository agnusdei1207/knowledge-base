# 📖 【암기용】 개념 완전 이해

> 목적: 탐욕 알고리즘을 지역 선택과 전역 최적성 증명 관점으로 이해하게 만든다.

## 한눈에
- **개요**: 매 단계에서 현재 기준으로 가장 유리한 선택을 해 전체 해를 구성하는 알고리즘 설계 기법
- **왜 필요한가**: 모든 조합을 탐색하면 경우의 수가 폭증하므로, 증명 가능한 선택 기준으로 O(n log n)~O(n) 수준의 해 구성 절차가 필요함
- **핵심 직관**: 지금 선택한 최선이 나중에도 손해가 되지 않는다는 조건이 있을 때만 사용함

## 깊이 이해
- **배경·문제의식**: 최적화 문제는 가능한 해 조합이 많다. 탐욕은 매 단계 하나의 선택을 고정해 탐색 공간을 줄이지만, 항상 정답을 보장하지 않음
- **작동 원리**: 후보 집합에서 선택 기준에 맞는 원소를 고르고, 제약을 만족하면 해 집합에 추가함. 교환 논증 또는 cut property로 전역 최적성을 증명함
- **비유**: 회의실 배정에서 종료 시간이 가장 이른 회의부터 잡으면 남은 시간 구간이 최대가 되어 전체 회의 수를 최대로 만들 수 있음
- **구체 예시**: 활동 선택 문제는 종료 시간 오름차순 정렬 후 겹치지 않는 활동을 선택하면 O(n log n)임. MST의 크루스칼도 간선 가중치 오름차순 탐욕 선택임
- **흔한 오해·주의점**: 배낭 문제에서 단가가 높은 물건부터 고르는 방식은 분할 가능 배낭에서는 정답이나 0/1 배낭에서는 반례가 존재함

## 연결 개념
- 최소 신장 트리 — 크루스칼·프림은 탐욕 선택의 대표 사례
- 동적 프로그래밍 — 탐욕 조건이 없으면 상태 기반 최적화 검토
- 증명 기법 — greedy-choice property, optimal substructure, exchange argument

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 탐욕 알고리즘은 현재 단계의 최선 선택을 누적해 해를 구성하는 최적화 설계 기법이다.
> 2. **가치**: 정렬 O(n log n)과 선형 스캔 O(n) 조합으로 많은 선택 문제를 낮은 계산량으로 해결한다.
> 3. **판단 포인트**: 탐욕 선택 속성과 최적 부분 구조가 증명되지 않으면 DP·백트래킹으로 전환해야 한다.

---

## Ⅰ. 개요 및 필요성

개요: 탐욕 알고리즘은 현재 최선 선택을 누적한다. 조합 최적화는 전체 경우의 수가 지수적으로 증가할 수 있다. 탐욕은 선택 기준을 고정해 계산량을 줄이되, 전역 최적성 증명이 있는 문제에 한해 적용해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Candidate Set -> Selection Rule -> Feasibility Check -> Solution Set -> Objective
              / Selection: current best candidate
              / Feasibility: constraint check
              / Proof: exchange argument or cut property
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 후보 집합 | 선택 가능한 원소 | 활동, 간선, 작업, 동전 |
| 선택 기준 | 현재 최선 원소 결정 | 최소 종료시간, 최소 가중치 |
| 제약 검사 | 해의 유효성 보장 | 겹침, 사이클, 용량 제한 |
| 증명 조건 | 전역 최적성 근거 | 교환 논증, cut property |

> 요약: 탐욕 알고리즘은 후보·선택 기준·제약 검사를 반복하고, 증명 조건으로 전역 최적성을 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
후보 정렬/선정 -> 현재 최선 선택 -> 제약 검사 -> 해 집합 추가 -> 종료/반복
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목적함수와 제약 조건 정의 | 최대/최소 기준 명확화 |
| 2 | 후보를 선택 기준으로 정렬 또는 PQ 구성 | O(n log n) 또는 O(log n) 추출 |
| 3 | 현재 최선 후보 선택·제약 확인 | feasible 여부 |
| 4 | 해 집합 갱신 후 최적성 검증 | 교환 논증 또는 반례 검사 |

> 요약: 탐욕은 선택 기준을 반복 적용하는 절차이며, 반례 검토와 최적성 증명이 알고리즘 채택의 핵심이다.

---

## Ⅳ. 특징

| 구분 | 탐욕 알고리즘 | 동적 프로그래밍 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 선택 방식 | 현재 최선 선택 고정 | 여러 상태의 최적값 저장 | 선택 되돌림 여부 |
| 시간복잡도 | 정렬 기반 O(n log n) 사례 다수 | 상태 수 x 전이 수 | 계산량 산정 방식 |
| 정답 보장 | 증명 조건 필요 | 점화식이 전체 상태 포괄 | 반례 존재 여부 |
| 대표 사례 | 활동 선택, 허프만, MST, 다익스트라 | 0/1 배낭, LCS | 문제 조건 |

> 요약: 탐욕은 증명 가능한 선택 기준이 있을 때 계산량이 작고, 반례가 있으면 DP나 완전탐색으로 전환한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | DP/완전탐색 | 탐욕 알고리즘 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 여러 후보 상태 보존 | 현재 최선 선택 고정 | greedy-choice property 증명 |
| 비용/성능 | 상태 수 또는 조합 수 증가 | 정렬 O(n log n)+스캔 O(n) | 반례 없고 선택 기준 명확 |
| 운영/위험 | 계산량 증가 | 최적성 증명 실패 시 오답 | 교환 논증·cut property 제시 |

> 요약: 탐욕은 계산량이 작지만, 전역 최적성 증명이 답안의 핵심 판단 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오답 선택 | 지역 최적이 전역 최적 미보장 | 반례 탐색, DP와 작은 입력 대조 | counterexample count |
| 제약 누락 | feasible 검사 부족 | 제약 조건을 선택 전후 검증 | invalid solution rate |
| 정렬 기준 오류 | 목적함수와 기준 불일치 | 교환 논증으로 정렬 기준 검증 | proof checklist 통과 |

> 요약: 탐욕 리스크는 최적성 증명, 제약 검증, 정렬 기준이며 작은 입력 대조로 보완한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 증명 | 교환 논증 또는 cut property 포함 | 설계 리뷰 |
| 복잡도 | 정렬·스캔 비용 분리 | 코드 리뷰 |
| 해 품질 | 작은 입력 정확해와 100% 일치 | brute force 테스트 |

> 요약: 성공 기준은 증명 가능성, 복잡도 분리, 작은 입력 정확해 대조이다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 스케줄링: 종료 시간 오름차순 활동 선택으로 회의실 1개에서 배정 가능한 작업 수를 최대화
2. 네트워크 설계: 크루스칼·프림으로 MST 산출, Union-Find로 사이클을 판정해 V-1개 간선 선택
3. 압축·라우팅: 허프만 코딩으로 빈도 기반 prefix code 생성, 다익스트라로 음수 간선 없는 경로 비용 계산

**결론 (2줄):**
- 기술사 판단: 탐욕 선택 속성이 증명되면 탐욕, 반례가 있거나 상태 의존성이 크면 DP, 제약 조합 탐색은 백트래킹을 선택함
- 향후 방향: 실무 최적화는 탐욕 휴리스틱으로 초기해를 만들고, ILP·메타휴리스틱·DP로 해 품질을 검증하는 방식이 필요함
