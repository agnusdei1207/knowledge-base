## 미리 알고가기

- 국소 최적해: 현재 단계에서 가장 좋아 보이는 선택임
- 탐욕적 선택 속성: 현재 최선 선택이 전체 최적해로 이어지는 성질임
- 교환 논증: 탐욕 선택의 정당성을 증명하는 대표 방법임

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘은 각 단계에서 가장 유리한 선택을 즉시 확정해 전체 문제를 해결하는 방식이며, 선택을 되돌리지 않는다는 점이 핵심임
- **배경/필요성**: 실시간 응답이나 대규모 입력 환경에서는 모든 경우를 비교하는 비용이 너무 크므로, 조건이 맞는 문제에서는 빠른 결정 전략이 필요함

## Ⅱ. 특징

- 선택을 즉시 확정하므로 구현이 단순하고 실행 속도가 빠름
- 최적해 보장은 탐욕적 선택 속성과 최적 부분 구조가 함께 성립할 때만 가능함
- 선택 기준이 명확한 스케줄링, 허프만 코딩, MST 같은 문제에서 강함
- 조건이 맞지 않으면 빠르게 오답을 만들 수 있으므로 증명이 없는 탐욕은 위험함

## Ⅲ. 종류 및 비교

| 판단 기준 | 탐욕 알고리즘 | 동적 프로그래밍 | 완전 탐색 |
|:---|:---|:---|:---|
| 선택 방식 | 즉시 확정 | 여러 상태 비교 | 모든 경우 조사 |
| 속도 | 빠름 | 중간 | 느림 |
| 정답 보장 | 조건 성립 시 | 상태 정의가 맞으면 보장 | 보장 |
| 적합 문제 | 선택 기준이 증명된 문제 | 중복 부분 문제 | 작은 입력의 정확 해 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 후보 집합 | 현재 단계에서 선택 가능한 원소들이며 정렬이나 우선순위화가 자주 필요함 |
| 선택 기준 | 이익 최대, 비용 최소, 종료 시각 최소 등이며 기준이 바뀌면 정답성이 무너질 수 있음 |
| 제약 검사 | 선택이 규칙을 위반하는지 확인하고 국소 최적이더라도 제약 위반은 제외함 |
| 누적 해 | 지금까지 확정된 부분 해이며 되돌리지 않는 구조를 가짐 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 후보 집합    | --> | 선택 기준    | --> | 제약 검사    | --> | 누적 해      |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 후보준비 | --> | 최선선택 | --> | 제약검사 | --> | 해확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **후보준비**: 선택 기준에 맞게 원소를 정렬하거나 우선순위를 부여함
2. **최선선택**: 현재 시점에서 가장 좋은 후보를 하나 고름
3. **제약검사**: 규칙을 위반하지 않으면 채택하고 아니면 건너뜀
4. **해확정**: 선택을 누적하고 다음 단계로 진행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 탐욕 선택 기준이 성립하지 않는 문제에서는 국소 최적이 전역 최적을 보장하지 않아 오답이 될 수 있음
   - 해결방안: 교환 논증이나 반례 검토로 정당성을 먼저 확인하고 반례 유무로 검증함
2. 문제: 정렬 기준을 잘못 잡으면 같은 문제라도 종료 시각, 이익률, 비용 중 무엇을 기준으로 두느냐에 따라 결과가 달라짐
   - 해결방안: 목표 함수와 직접 연결되는 기준을 정의하고 목적 함수 값으로 검증함
3. 문제: 근사 품질을 설명하지 못해 최적해가 아닌 경우 품질 한계를 제시하지 못하면 설계 설득력이 약함
   - 해결방안: 근사비 또는 경험적 품질 지표를 함께 제시하고 최적해 대비 오차율로 검증함

## Ⅶ. 적용 사례

- 작업 스케줄링에서는 종료 시각이 빠른 작업부터 선택해 충돌을 줄이며, 처리 건수와 자원 가동률로 결과를 확인함
- 데이터 압축에서는 허프만 코딩으로 빈도가 높은 문자에 짧은 코드를 부여하며, 평균 코드 길이와 압축률로 결과를 확인함
- 네트워크 구축에서는 최소 간선 비용 선택을 반복해 연결망 비용을 줄이며, 총 비용과 연결성으로 결과를 확인함

## Ⅷ. 결론

탐욕 알고리즘은 빠르다는 이유만으로 쓰는 기법이 아니라 현재 선택이 왜 전체 최적과 연결되는지 설명할 수 있을 때만 써야 하는 기법임.
