## 미리 알고가기

- **탐욕적 선택 속성 ($Greedy$ $Choice$ $Property$)**: 이전의 선택이 이후의 선택에 영향을 주지 않으며, 매 순간의 최적해가 전체의 최적해로 이어지는 성질임
- **최적 부분 구조 ($Optimal$ $Substructure$)**: 큰 문제의 최적해가 부분 문제들의 최적해들의 결합으로 구성되는 성질임
- **교환 논증 ($Exchange$ $Argument$)**: 탐욕적인 선택이 아닌 다른 해가 있다면, 이를 탐욕적인 선택으로 바꾸어도 해의 품질이 나빠지지 않음을 보여 최적성을 증명하는 기법임

## Ⅰ. 개요

- **정의/개념**: 문제를 해결하는 매 단계에서 가장 이익이 크거나 비용이 적은 선택($Local$ $Optimal$)을 반복하여 최종적인 해답($Global$ $Optimal$)에 도달하려는 알고리즘 설계 기법임
- **배경/필요성**: 모든 경우의 수를 탐색하는 완전 탐색이나 표를 채우는 $DP$는 대규모 데이터에서 연산 부하가 극심함. 탐욕 알고리즘은 연산량을 획기적으로 줄여 실시간 응답성을 확보하고, $NP-Hard$ 문제에 대해 수용 가능한 수준의 근사해($Approximation$)를 신속히 제공함

## Ⅱ. 특징 및 비교

### 가. 알고리즘 설계 패러다임 기술 비교

| 비교 항목 | 탐욕 알고리즘 ($Greedy$) | 동적 계획법 ($DP$) | 완전 탐색 ($Brute-force$) |
|:---|:---|:---|:---|
| **결정 방식** | **매 단계 최선 하나를 확정** | 여러 후보 비교 후 최적 선택 | 모든 경우의 수 조사 |
| **속도/비용** | **가장 빠름 ($O(n \log n)$ 이하)** | 중간 (상태 공간 비례) | 매우 느림 (지수 시간) |
| **정답 보장** | 탐욕 속성 성립 시에만 보장 | **항상 보장** | 항상 보장 |
| **처리 방향** | 상향식 ($Bottom-up$) | 하향식/상향식 혼용 | 전수 조사 |
| **선택 번복** | **불가능 (한 번 정하면 끝)** | 가능 (이전 단계 고려) | 해당 없음 |

> 요약: 정답의 정확성이 절대적이면 $DP$, 속도와 효율성이 최우선이면 $Greedy$가 적합함.

### 나. 아키텍처 인사이트: $Trade-off$

- **효율성 vs 정확성**: 탐욕법은 연산 복잡도를 낮추는 대신 해의 품질($Quality$)을 일부 희생함. 단, 허프만 코딩이나 $MST$처럼 탐욕 속성이 증명된 도메인에서는 무결한 최적해를 보장함
- **결정적($Deterministic$) 설계**: 선택 기준이 명확하여 구현이 단순하고 시스템 자원 예측이 용이함

## Ⅲ. 구성요소/구조

### 가. 탐욕 알고리즘의 4대 구성 요소

1. **후보 집합 ($Candidate$ $Set$)**: 현재 단계에서 선택 가능한 모든 해의 원소 모음
2. **선택 절차 ($Selection$ $Procedure$)**: 현재 상태에서 가장 '탐욕적인' 기준(최대 이익, 최소 비용 등)에 따라 후보를 고름
3. **적합성 검사 ($Feasibility$ $Check$)**: 선택된 후보가 문제의 제약 조건(예: 무게 제한)을 위반하는지 확인
4. **해 검사 ($Solution$ $Check$)**: 최종 구성된 해가 원래 문제의 요구사항을 충족하는지 검증

### 나. 처리 아키텍처 (프로세스)

- **정렬/우선순위화**: 후보군을 탐욕 기준에 따라 정렬 ($O(n \log n)$)
- **순차적 선택**: 정렬된 순서대로 후보를 추출하며 해 집합에 추가
- **제약 조건 필터링**: 적합하지 않은 후보는 즉시 폐기하고 다음 후보로 이동

## Ⅳ. 문제점 및 개선방안

1. **국소 최적해 ($Local$ $Optimum$)의 함정**: 현재의 최선이 미래의 큰 손실을 초래하여 전역 최적해를 놓칠 수 있음
   - **개선방안**: 탐욕적 선택 속성을 수학적으로 검증($Exchange$ $Argument$)하거나, 실패 시 $Backtracking$ 또는 $DP$로 설계 전환
2. **근사해의 품질 보장 불확실**: $NP-Hard$ 문제 적용 시 최적해와의 오차 범위를 알기 어려움
   - **개선방안**: 해당 문제의 **근사비 ($Approximation$ $Ratio$)**를 분석하여 최악의 경우에도 허용 가능한 오차 한계($Bound$) 내에 있는지 사전 검증
3. **빈번한 정렬 오버헤드**: 데이터가 실시간으로 추가되는 환경에서 매번 정렬하는 비용 발생
   - **개선방안**: **우선순위 큐 ($Priority$ $Queue$)**를 활용하여 $O(\log n)$ 복잡도로 최적 후보를 상시 유지

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **데이터 압축 (Huffman)** | 빈도 낮은 문자부터 결합하여 가변 길이 코드 할당 | 압축률, 평균 코드 길이 |
| **인프라 최적화 (MST)** | 최소 가중치 간선부터 선택하여 전체망 연결 | 포설 비용($CAPEX$), 연결성 |
| **작업 스케줄링** | 종료 시간이 가장 빠른 작업부터 우선 배정 | 자원 가동률, 단위 시간당 처리량 |
| **비디오 스트리밍 (ABR)** | 네트워크 대역폭에 맞춰 매 순간 최적 화질 선택 | 재생 끊김 횟수, 평균 비트레이트 |

## Ⅵ. 결론

탐욕 알고리즘은 **'최적을 향한 직관'**을 알고리즘화하여 실행 속도를 극대화하는 강력한 도구임. 기술사는 단순히 기법을 적용하는 것에 그치지 않고, 대상 문제의 **탐욕적 선택 속성** 성립 여부를 엄밀히 판정할 수 있어야 함. 만약 최적해 보장이 어렵더라도 실무적으로 허용 가능한 **근사 오차 범위**를 제시하고, 필요시 $A^*$ 탐색이나 빔 서치($Beam$ $Search$) 등과 결합하여 해의 신뢰성을 보완하는 아키텍처 설계 역량을 발휘해야 함.
