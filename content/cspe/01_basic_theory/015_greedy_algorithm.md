## 미리 알고가기

- 국소 최적해: 현재 단계에서 가장 좋아 보이는 선택임
- 전역 최적해: 문제 전체를 기준으로 가장 좋은 최종 답임
- 탐욕적 선택 속성: 현재 최선 선택이 전체 최적해로 이어지는 성질임
- 교환 논증: 최적해의 일부를 탐욕 선택으로 바꿔도 손해가 없음을 보이는 증명 방법임

## Ⅰ. 개요

- **정의/개념**: 탐욕 알고리즘은 각 단계에서 현재 기준으로 가장 좋은 선택을 즉시 확정해 답을 만들어 가는 알고리즘 설계 기법임
- **배경/필요성**: 모든 경우의 수를 비교하기 어려운 문제에서는 빠른 선택 기준이 필요함. 단, 그 선택이 전체 최적해로 이어져야 정확 해법으로 쓸 수 있음

## Ⅱ. 특징

- 한 번 선택한 결과를 되돌리지 않으므로 구현이 단순하고 빠름
- 선택 기준이 잘못되면 초반 결정의 오류가 끝까지 누적됨
- 탐욕적 선택 속성과 최적 부분 구조가 성립해야 최적해를 보장함
- 증명 없이 직관으로만 적용하면 작은 반례에도 깨질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 탐욕 알고리즘 | 동적 프로그래밍 | 완전 탐색 |
|:---|:---|:---|:---|
| 선택 방식 | 현재 최선 후보를 확정함 | 여러 상태를 비교해 누적 계산함 | 가능한 경우를 모두 확인함 |
| 되돌림 | 없음 | 상태 전이에 따라 간접 반영 | 모든 경로를 확인 |
| 계산 비용 | 낮은 편 | 상태 수에 비례 | 경우의 수에 비례 |
| 정답 보장 | 탐욕 선택 속성이 필요함 | 점화식이 맞아야 함 | 입력이 작으면 보장 가능 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 후보 집합 | 아직 선택하지 않은 항목들의 모음임 |
| 선택 기준 | 후보의 우선순위를 정하는 비교 규칙임 |
| 가능성 검사 | 선택이 제약 조건을 깨는지 확인함 |
| 확정 해 | 선택된 항목들이 누적된 결과임 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 후보 집합 | --> | 기준 비교 | --> | 제약 확인 | --> | 선택 확정 |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 후보 정렬 | --> | 최선 선택 | --> | 가능성 검사 | --> | 해에 추가 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 선택 기준에 따라 후보를 비교함
2. 현재 가장 좋은 후보를 고름
3. 제약 조건을 어기지 않는지 확인함
4. 가능하면 확정하고 다음 단계로 진행함

## Ⅵ. 실무 적용 및 유의점

1. 스케줄링이나 자원 배분에 탐욕 기준을 쓸 때는 교환 논증이나 반례 테스트로 최적성 근거를 확인해야 함
2. 정확 해법이 아니라 휴리스틱으로 쓰는 경우에는 최적해 보장 대신 결과 품질과 계산시간을 함께 측정해야 함

## Ⅶ. 결론

- 탐욕 알고리즘은 빠른 선택이 장점이지만, 현재 최선 선택이 전체 최적해로 이어진다는 근거가 있어야 정확하게 쓸 수 있음
