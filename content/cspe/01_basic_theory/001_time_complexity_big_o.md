## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 입력 크기 `n`이 증가할 때 알고리즘의 연산 횟수 증가율을 점근적 상한으로 표기하는 분석 기법임 |
| **배경/필요성** | 하드웨어 독립적인 알고리즘 성능 비교 기준이 필요하며, 데이터 규모 증가에 따른 실행 시간 예측이 필수임 |
| **출제 의도** | Big-O 도출 과정과 주요 복잡도 클래스 간 성능 차이를 정량적으로 설명할 수 있는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 입력크기  | --> | 기본연산  | --> | 점근상한  |
|   (n)    |     | (비교/교환)|    |  O(f(n)) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 입력 크기(n) | 알고리즘이 처리하는 데이터 원소의 개수임 | 요리할 재료 수량 |
| 기본 연산 | 비교·대입·산술 등 실행 시간을 좌우하는 핵심 단위 연산임 | 칼질 1회 동작 |
| 점근적 상한 O(f(n)) | n → ∞일 때 연산 횟수의 최악 증가율 상한을 나타내는 함수임 | 최대 소요 시간 보증서 |

> 요약: 입력 크기(n)에 대한 기본 연산 횟수의 점근적 상한을 O 표기로 나타내어 알고리즘 확장성을 평가함.

## Ⅲ. 절차
```
+------------+     +------------+
| 핵심연산   | --> | 연산횟수   |
| 식별       |     | f(n) 도출  |
+------------+     +------------+
                        |
+------------+     +----+-------+
| O(g(n))   | <-- | 최고차항  |
| 표기       |     | 추출·계수제거|
+------------+     +------------+
```

1. 핵심 연산 식별: 반복문 내부의 비교·교환 등 수행 빈도가 가장 높은 연산을 파악함
2. 연산 횟수 도출: 반복 횟수를 n의 함수 `f(n) = 3n² + 5n + 2`와 같이 다항식으로 표현함
3. 최고차항 추출: 증가율을 지배하는 최고차항(`n²`)만 남기고 하위항을 제거함
4. 계수 제거·표기: 상수 계수를 제거하고 `O(n²)`로 표기하여 점근적 상한을 확정함

> 요약: 핵심 연산 식별 → 다항식 도출 → 최고차항 추출 → 계수 제거로 Big-O를 결정함.

## Ⅳ. 문제점
- 상수 은닉: 계수·하위항 제거로 `O(n)` 알고리즘이 실제로는 `100n`이어서 소규모 입력에서 `O(n²)`보다 느릴 수 있음
- 최악 편향: 평균·최선 사례(Ω, Θ)를 반영하지 못해 실 운영 성능과 괴리가 발생함
- 시스템 요인 배제: 캐시 적중률·분기 예측·메모리 계층 등 하드웨어 특성이 분석에서 누락됨

## Ⅴ. 개선방안
- (단기) Θ·Ω 병행 분석: 최선·평균·최악 복잡도를 함께 제시하여 편향을 보완함
- (중기) 프로파일링 병행: 이론 분석과 실 환경 벤치마크를 결합하여 상수·캐시 영향을 검증함
- (장기) 머신별 복잡도 모델: 캐시 계층·병렬도를 반영한 External Memory·I/O 복잡도 모델을 적용함

## Ⅵ. 전망
- GPU·NPU 등 이기종 가속기 확산에 따라 연산·메모리·통신 복잡도를 분리 분석하는 다차원 복잡도 모델이 표준화될 전망임
