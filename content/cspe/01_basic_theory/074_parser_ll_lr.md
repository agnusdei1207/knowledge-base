## 미리 알고가기

- top-down: 시작 기호에서 입력으로 내려가는 파싱 방식임
- bottom-up: 입력에서 시작해 상위 구조로 축약하는 방식임
- lookahead: 다음 토큰을 미리 보는 개수임

## Ⅰ. 개요

- **정의/개념**: LL과 LR은 문맥 자유 문법을 파싱하는 대표 방식으로, LL은 top-down 예측 파싱이고 LR은 bottom-up shift-reduce 파싱임
- **배경/필요성**: 프로그래밍 언어 구문을 정확히 인식하려면 문법뿐 아니라 그것을 효율적으로 처리할 파싱 전략이 필요함

## Ⅱ. 특징

- LL은 구현과 이해가 단순하고 재귀 하향 파서에 적합함
- LR은 더 넓은 문법을 다루며 실무 언어 처리에 강함
- LL은 좌재귀 제거가 필요하고 LR은 상태표 기반 구현이 일반적임
- 충돌 관리와 오류 복구 설계가 파서 품질을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | LL | LR |
|:---|:---|:---|
| 파싱 방향 | 좌에서 우로 읽고 좌파생 | 좌에서 우로 읽고 우파생 역추적 |
| 방식 | 예측 파싱 | shift-reduce |
| 장점 | 단순, 직접 구현 용이 | 표현력 높음 |
| 주의점 | 좌재귀 불가 | 구현 복잡, 충돌 처리 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 버퍼 | 토큰열을 보관하고 파서의 현재 위치 기준임 |
| 파싱 스택 | 기호나 상태를 저장하고 진행 문맥을 유지함 |
| 파싱 테이블 | 규칙 선택 기준이며 자동 생성 핵심임 |
| 액션 규칙 | expand 또는 shift/reduce를 수행하고 실제 파싱 로직임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 토큰읽기 | --> | 규칙선택 | --> | 전개/축약 | --> | 수용판정 |
+----------+     +----------+     +----------+     +----------+
```

1. **토큰읽기**: 현재 lookahead를 확인함
2. **규칙선택**: 파싱 테이블에 따라 적용 규칙을 고름
3. **전개/축약**: LL은 비단말 전개, LR은 shift/reduce를 수행함
4. **수용판정**: 입력이 문법 구조에 맞으면 수용함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 문법 충돌이 발생해 LL은 first/follow 충돌, LR은 shift/reduce 충돌이 생김
   - 해결방안: 문법 리팩터링과 우선순위 선언을 적용하고 conflict count로 검증함
2. 문제: 오류 복구가 어려워 하나의 토큰 오류가 뒤 전체를 무너뜨릴 수 있음
   - 해결방안: panic mode와 동기화 토큰을 설계하고 recovery success rate로 검증함
3. 문제: 문법 유지보수가 복잡해질 수 있어 기능 확장 때 규칙 영향 범위가 큼
   - 해결방안: 모듈식 문법과 자동 생성기를 사용하고 grammar diff impact로 검증함

## Ⅶ. 적용 사례

- 재귀 하향 파서: DSL과 교육용 언어에 LL을 사용함, 확인 지표는 구현 단순성임
- C 계열 언어 파서: LR 계열 생성기를 활용함, 확인 지표는 문법 수용 범위임
- 정적 분석 도구: AST 생성용 파서를 구현함, 확인 지표는 파싱 정확도임

## Ⅷ. 결론

LL과 LR의 핵심 차이는 표현력과 구현 복잡도이므로, 언어 문법 수준과 유지보수 비용을 함께 보고 파서 방식을 선택해야 함.
