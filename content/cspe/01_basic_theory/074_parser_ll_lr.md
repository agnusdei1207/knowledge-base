## 미리 알고가기

- 파싱(Parsing): 토큰열이 문법 규칙에 맞는지 확인하고 구문 트리를 만드는 절차임
- 하향식 파싱: 시작 기호에서 입력 토큰 방향으로 규칙을 전개하는 방식임
- 상향식 파싱: 입력 토큰을 묶어 시작 기호로 환원하는 방식임
- 좌재귀: 규칙이 자기 자신을 왼쪽 첫 기호로 다시 부르는 구조임
- 시프트/리듀스: LR 파서에서 토큰을 쌓거나 규칙으로 줄이는 기본 동작임
- 패닉 모드: 오류 뒤의 입력을 동기화 토큰까지 건너뛰고 분석을 재개하는 복구 방식임

## 작성 근거(검토용)

- 개요는 파서를 토큰열과 문법 규칙 사이의 판정기로 정의해 컴파일러 내 위치를 명확히 함
- 특징은 하향식·상향식 차이, 파싱 테이블, 충돌 처리를 LL/LR 선택 기준으로 선정함
- Ⅲ은 분석·유도 방향, 동작, 문법 처리 조건, 구현 방식, 대표 적용 사례로 두 파서의 차이를 드러냄
- Ⅳ는 토큰·룩어헤드·테이블·스택·AST의 역할을 정리하고 Ⅴ는 LL·LR의 상태 전이를 분리함
- 충돌 해결과 오류 복구는 파서 품질을 좌우하는 핵심 판단임

## Ⅰ. 개요

- **정의/개념**: LL·LR 파서는 토큰열을 문법 규칙과 대조해 구문 구조를 판정하는 대표 구문 분석 방식임
- **배경/필요성**: 올바른 프로그램 구조만 AST로 넘기기 위해 문법 충돌과 모호성을 제어하는 파싱 방식이 필요함

## Ⅱ. 특징

- LL은 생성 규칙과 재귀 하강 함수를 대응시켜 직접 구현할 수 있음
- LR은 입력 토큰을 스택에 쌓아 환원하며 LL보다 넓은 결정적 문맥 자유 문법을 처리함
- 파싱 테이블은 현재 비단말 또는 상태와 룩어헤드로 다음 동작을 결정함
- 좌재귀, 우선순위, 결합 법칙 처리가 파서 충돌을 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | LL 파서 | LR 파서 |
|:---|:---|:---|
| 분석·유도 방향 | 시작 기호에서 입력으로 좌측 유도 | 입력에서 시작 기호로 우측 유도를 역순 환원 |
| 주요 동작 | 예측·규칙 확장 | 시프트·리듀스·수용 |
| 문법 처리 조건 | 좌재귀 제거·예측 충돌 해소를 위한 좌인수분해 | 좌재귀 허용·시프트/리듀스 충돌 통제 |
| 구현 방식 | 재귀 하강·예측 테이블 | 파서 생성기(Yacc/Bison) |
| 대표 적용 사례 | 설정·도메인 특화 언어 파서 | 프로그래밍 언어 컴파일러 파서 |

> 요약: 좌재귀를 제거해 재귀 하강으로 구현하면 LL, 좌재귀를 유지하고 파서 생성기를 사용하면 LR을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 토큰 스트림 | 어휘 분석기가 넘긴 입력 단위이며 파서의 검사 대상임 |
| 파싱 스택 | LL의 기호 또는 LR의 상태와 기호를 저장함 |
| 룩어헤드 | 현재 결정에 참고하는 다음 입력 토큰임 |
| 파싱 테이블 | 상태와 토큰 조합별 동작을 정의함 |
| AST 빌더 | 문법 규칙이 확정될 때 구문 노드를 생성함 |

> 요약: 파서는 룩어헤드와 문법 규칙으로 입력 토큰을 판정하고 AST를 구성함.

## Ⅴ. 원리 및 절차 흐름도

```text
[LL] 룩어헤드 -> 생성 규칙 선택 -> 비단말 전개·단말 일치 -> 수용·오류
[LR] 상태+룩어헤드 -> 시프트·리듀스 선택 -> 상태 스택 갱신 -> 수용·오류
```

1. **LL 파싱**: 룩어헤드로 생성 규칙을 선택하고 비단말 전개와 단말 일치를 반복함
2. **LR 파싱**: 현재 상태와 룩어헤드로 시프트·리듀스를 선택하고 상태 스택을 갱신함

> 요약: LL은 생성 규칙을 예측 전개하고 LR은 입력을 상태 스택에서 환원하므로 문법 제약과 파싱 충돌에 따라 선택함.

## Ⅵ. 실무 사례

1. LR 파서 생성은 우선순위·결합 법칙을 명시하고 시프트/리듀스 충돌 수로 검증함
2. 컴파일러 파서는 패닉 모드로 토큰을 동기화하고 복구 성공률·오류 위치 정확도로 검증함

## Ⅶ. 결론

- 파서는 언어 문법의 제약과 구현 방식을 기준으로 LL·LR을 선택하고 파싱 충돌과 오류 복구를 검증해야 함
