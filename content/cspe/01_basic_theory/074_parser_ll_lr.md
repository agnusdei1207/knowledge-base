## 미리 알고가기

- 파싱(Parsing): 토큰열이 문법 규칙에 맞는지 확인하고 구문 트리를 만드는 절차임
- 하향식 파싱: 시작 기호에서 입력 토큰 방향으로 규칙을 전개하는 방식임
- 상향식 파싱: 입력 토큰을 묶어 시작 기호로 환원하는 방식임
- 좌재귀: 규칙이 자기 자신을 왼쪽 첫 기호로 다시 부르는 구조임
- 시프트/리듀스: LR 파서에서 토큰을 쌓거나 규칙으로 줄이는 기본 동작임

## 작성 근거(검토용)

- 개요는 파서를 토큰열과 문법 규칙 사이의 판정기로 정의해 컴파일러 내 위치를 명확히 함
- 특징은 하향식·상향식 차이, 파싱 테이블, 충돌 처리를 LL/LR 선택 기준으로 선정함
- Ⅲ은 분석 방향, 유도 기준, 동작, 수용력, 구현 방식, 대표 적용 사례로 두 파서의 차이를 간결하게 드러냄
- 구조 도식은 토큰, 룩어헤드, 테이블, 스택, AST의 관계가 파서 동작 이해에 필요하므로 배치함
- 충돌 해결과 오류 복구는 파서 품질을 좌우하는 핵심 판단임

## Ⅰ. 개요

- **정의/개념**: LL·LR 파서는 토큰열을 문법 규칙과 대조해 구문 구조를 판정하는 대표 구문 분석 방식임
- **배경/필요성**: 올바른 프로그램 구조만 AST로 넘기기 위해 문법 충돌과 모호성을 제어하는 파싱 방식이 필요함

## Ⅱ. 특징

- LL은 시작 기호에서 예측 전개하므로 구현과 오류 추적이 직관적임
- LR은 입력 토큰을 스택에 쌓아 환원하므로 더 넓은 문법을 처리함
- 파싱 테이블은 현재 기호와 룩어헤드로 다음 동작을 결정함
- 좌재귀, 우선순위, 결합 법칙 처리가 파서 충돌을 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | LL 파서 | LR 파서 |
|:---|:---|:---|
| 분석 방향 | 하향식 전개 | 상향식 환원 |
| 유도 기준 | 좌측 유도 | 우측 유도의 역순 |
| 주요 동작 | 예측, 규칙 확장 | Shift, Reduce, Accept |
| 문법 수용력 | 좌재귀 처리 어려움 | 더 넓은 CFG 처리 |
| 구현 방식 | 재귀 하강, 예측 테이블 | Yacc/Bison 계열 생성기 |
| 대표 적용 사례 | 설정 언어·간단한 DSL 파서 | 프로그래밍 언어 컴파일러 파서 |

> 요약: 손작성과 단순 문법은 LL, 복잡한 언어 문법은 LR이 적합함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 토큰 읽기 | --> | 동작 결정 | --> | 스택 갱신 | --> | AST 확정 |
+----------+     +----------+     +----------+     +----------+
```

1. **토큰 읽기**: 현재 입력과 룩어헤드를 확인함
2. **동작 결정**: LL은 생성 규칙, LR은 Shift/Reduce 동작을 선택함
3. **스택 갱신**: 전개 또는 환원 결과를 파싱 스택에 반영함
4. **AST 확정**: 시작 기호와 입력 끝이 맞으면 구문 트리를 반환함

> 요약: LL·LR 선택은 문법 복잡도와 충돌 처리 방식에 맞춰 AST 생성 안정성을 확보하는 문제임.

## Ⅵ. 실무 사례

1. LR 파서 생성 시 충돌이 나면 우선순위·결합 법칙을 명시하고 shift/reduce 충돌 수로 검증함
2. 컴파일러는 첫 오류에서 중단하면 수정 반복이 늘어나므로 패닉 모드로 토큰을 동기화하고 복구 성공률·오류 위치 정확도로 확인함

## Ⅶ. 결론

- 파서는 언어 문법의 복잡도와 구현 방식을 기준으로 LL·LR을 선택하고 충돌 없는 AST 생성을 보장해야 함
