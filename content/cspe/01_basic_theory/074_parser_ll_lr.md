## 미리 알고가기

- 파싱(Parsing): 토큰열의 문법 규칙 일치 여부를 검증하고 구문 트리를 만드는 절차임
- 하향식·상향식 파싱: 하향식은 시작 기호에서 입력 방향으로 규칙을 전개하고, 상향식은 입력 토큰을 묶어 시작 기호로 환원하는 방식임
- 좌재귀: 규칙이 자기 자신을 왼쪽 첫 기호로 다시 부르는 구조임
- FIRST·FOLLOW 집합: FIRST는 비단말이 유도하는 문자열의 첫 단말 집합이고, FOLLOW는 비단말 뒤에 올 수 있는 단말 집합임
- 시프트·리듀스: LR 파서에서 토큰을 쌓거나 규칙으로 줄이는 기본 동작임
- 핸들(Handle): 상향식 파싱에서 스택 상단이 생성 규칙 우변과 일치해 리듀스 대상이 되는 부분임
- 패닉 모드: 오류 뒤의 입력을 동기화 토큰까지 건너뛰고 분석을 재개하는 복구 방식임
- 룩어헤드: 파싱 동작을 결정할 때 참조하는 다음 입력 토큰임
- 파싱 테이블: 현재 비단말 또는 상태와 룩어헤드로 다음 파싱 동작을 정하는 표임
- 우선순위·결합 규칙: 우선순위는 연산자 적용 순서를, 결합 규칙은 같은 우선순위 연산자가 묶이는 방향을 정함

## 작성 근거(검토용)

- **방향성**: LL·LR 파서는 좌재귀 제거와 파싱 테이블 구성 복잡도를 맞바꾸므로, 좌재귀를 제거할 수 있는 단순 문법은 LL로 직접 구현하고 좌재귀·복잡한 문맥 자유 문법을 그대로 쓰려면 파서 생성기 기반 LR을 선택해야 함
- **Ⅰ. 개요 구성**: 파서를 토큰열과 문법 규칙을 대조하는 판정기로 정의하며 하향식·상향식을 구분하고, 충돌·모호성 제어의 필요성을 배경으로 제시함
- **Ⅱ. 특징 선정**: LL·LR의 구현 방식, 파싱 테이블, 좌재귀·충돌 처리를 선택 기준으로 선정함
- **Ⅲ. 비교축 선정**: 분석 메커니즘(LL(1)/SLR·LALR·LR(1) 계열 포함), 좌재귀 처리, 주요 리스크는 두 파서의 고유 스펙이라 축은 유지하고, 좌재귀 유무·문법 복잡도에 따른 선택 기준은 요약 문장의 구체적 분기 조건으로 명시함
- **Ⅳ. 구조 선정**: 토큰·룩어헤드·파싱 테이블·스택·AST의 역할을 정리함
- **Ⅴ. 절차 선정**: FIRST·FOLLOW 기반 예측과 핸들 인식 기반 환원으로 LL·LR 절차를 분리함
- **Ⅵ. 사례 선정**: 충돌 해결과 오류 복구는 파서 품질을 좌우하는 핵심 판단임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 우선순위·결합 규칙의 표기를 본문과 일치시켰으며 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: LL·LR 파서는 각각 하향식·상향식으로 토큰열을 문법 규칙과 대조해 구문 구조를 판정하는 대표 구문 분석 방식임
- **배경/필요성**: 올바른 프로그램 구조만 AST로 넘기기 위해 문법 충돌과 모호성을 제어하는 파싱 방식이 필요함

### 쉽게 이해하기 (학습용)
- 문장을 앞에서부터 읽으며 다음에 올 규칙을 미리 짐작하는 방법(LL)과, 단어들을 일단 쌓아두다가 규칙에 맞는 덩어리가 보이면 그때 묶는 방법(LR) 중 하나로 문장 구조를 판정함

## Ⅱ. 특징

- LL은 생성 규칙과 재귀 하강 함수를 대응시켜 직접 구현할 수 있음
- LR은 입력 토큰을 스택에 쌓아 환원하며 LL보다 넓은 결정적 문맥 자유 문법을 처리함
- 파싱 테이블은 현재 비단말 또는 상태와 룩어헤드로 다음 동작을 결정함
- LR은 파싱 테이블 구성이 복잡해 파서 생성기로 자동화함

### 쉽게 이해하기 (학습용)
- LL은 규칙 하나하나를 함수 하나씩으로 직접 옮겨 짤 수 있어 손으로도 만들기 쉬움
- LR은 단어를 쌓아두었다가 필요할 때 묶어내는 방식이라 더 다양한 문장 구조를 다루지만, 표를 짜는 일이 복잡해 자동 생성 도구를 씀

## Ⅲ. 종류 및 비교

| 판단 기준 | LL 파서 | LR 파서 |
|:---|:---|:---|
| 분석 메커니즘 | 좌측 유도·예측(LL(1)) | 우측 유도 역순 환원(SLR·LALR·LR(1)) |
| 좌재귀 처리 | 좌재귀 제거 필요 | 좌재귀 허용 |
| 주요 리스크 | 예측 충돌 | 시프트·리듀스 충돌 |

> 요약: 좌재귀를 제거할 수 있는 단순 문법을 직접 구현하려면 LL을, 좌재귀를 유지하며 폭넓은 문맥 자유 문법을 처리하려면 파서 생성기 기반 LR을 선택함.

### 쉽게 이해하기 (학습용)
- LL은 다음에 뭐가 나올지 앞을 내다보며 왼쪽부터 순서대로 조립하므로 자기 자신을 다시 부르는 규칙을 미리 없애둬야 하고, LR은 일단 쌓아두었다가 뒤에서부터 거슬러 묶어가므로 그런 규칙도 그대로 둘 수 있음

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 토큰 스트림 | 어휘 분석기가 전달한 파싱 입력 |
| 파싱 스택 | LL 기호·LR 상태의 저장 공간 |
| 룩어헤드 | 파싱 동작을 결정하는 다음 토큰 |
| 파싱 테이블 | 상태·토큰별 동작 매핑 |
| AST 빌더 | 확정된 문법 규칙의 구문 노드 생성기 |

> 요약: 파서는 룩어헤드와 파싱 테이블로 토큰열의 문법을 판정하고 AST를 구성함.

### 쉽게 이해하기 (학습용)
- 다음 단어(룩어헤드)를 표(파싱 테이블)에 대조해 다음 행동을 정하고, 그 결과를 계속 쌓아 최종 구조도(AST)를 완성함

## Ⅴ. 원리 및 절차 흐름도

```text
[LL] 룩어헤드 -> FIRST·FOLLOW 대조 -> 생성 규칙 선택 -> 비단말 전개·단말 일치 -> 수용·오류
[LR] 상태+룩어헤드 -> 핸들 인식 -> 시프트·리듀스 선택 -> 상태 스택 갱신 -> 수용·오류
```

1. **LL 파싱**: 룩어헤드를 생성 규칙의 FIRST·FOLLOW 집합과 대조해 규칙을 선택하고 비단말 전개와 단말 일치를 반복함
2. **LR 파싱**: 스택 상단에서 핸들을 인식하면 리듀스하고, 아니면 시프트해 상태 스택을 갱신함

> 요약: LL은 FIRST·FOLLOW로 생성 규칙을 예측 전개하고 LR은 핸들 인식으로 상태 스택을 환원하므로 문법 제약과 파싱 충돌에 따라 선택함.

### 쉽게 이해하기 (학습용)
- LL은 다음 단어가 어떤 규칙으로 시작할 수 있는지 미리 정한 목록과 비교해 규칙을 고르고, LR은 지금까지 쌓아둔 단어 더미가 규칙과 딱 맞아떨어지는 순간에만 하나로 묶음

## Ⅵ. 실무 사례

1. LR 파서 생성기는 우선순위·결합 규칙으로 시프트·리듀스 충돌을 해소함
2. 컴파일러 파서는 오류 시 세미콜론·닫는 괄호까지 건너뛰는 패닉 모드로 분석을 재개함

### 쉽게 이해하기 (학습용)
- 헷갈리는 상황은 미리 정한 우선순위·결합 규칙으로 정리하고, 오류가 나면 세미콜론 같은 확실한 표시까지 건너뛰고 다시 읽기 시작함

## Ⅶ. 결론

- 파서는 토큰열을 문법 규칙과 대조해 구문 구조를 판정하며, 좌재귀를 제거할 수 있는 단순 문법은 LL로 직접 구현하고 좌재귀·복잡한 문맥 자유 문법을 그대로 쓰려면 LR을 선택해야 함
- 파싱 충돌은 우선순위 선언으로 숨기기 전에 문법을 재구성하고, 오류 복구가 후속 진단을 왜곡하지 않는지 검증해야 함

### 쉽게 이해하기 (학습용)
- 문장 구조가 단순하면 앞을 내다보는 방식(LL), 복잡하면 쌓았다 묶는 방식(LR)을 고르되, 헷갈리는 부분은 임시방편으로 덮지 말고 규칙 자체를 다시 손봐야 함
