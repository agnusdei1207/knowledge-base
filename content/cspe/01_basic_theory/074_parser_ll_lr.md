## Ⅰ. 개요
- 정의: 토큰 열을 입력받아 정해진 문법 구조(Parse Tree)를 구축하는 알고리즘임.
- 배경: 복잡한 프로그래밍 문법을 효율적으로 해석하기 위해 하향식/상향식 기법 발달함.
- 출제 의도:
| 분류 | 상세 |
| --- | --- |
| 핵심요소 | 유도(Derivation), 스택, 핸들, 선독(Lookahead) |
| 주요특징 | 구현 난이도, 문법 범위, 파싱 효율성 |

## Ⅱ. 구성요소
- ASCII 구조도
 [LL: Top-down]         [LR: Bottom-up]
     (Root)                 (Leaves)
      /  \       vs          /  \
   (Leaves)                 (Root)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| LL 파서 | 왼쪽에서 오른쪽으로, 최좌측 유도 수행 | 위에서 아래로 조립 |
| LR 파서 | 왼쪽에서 오른쪽으로, 최우측 유도 역순 | 아래에서 위로 조립 |
| 파싱 테이블 | 현재 상태와 입력 토큰에 따른 동작을 정의 | 지도/매뉴얼 |
> 요약: 입력 방향과 트리 구축 방향에 따라 상반된 전략을 사용함.

## Ⅲ. 절차
- ASCII 흐름도
[토큰 입력] -> [스택 조작] -> [상태 전이] -> [트리 완성]
- 4단계 설명
1. 초기화: 스택에 시작 심볼을 넣고 입력을 준비함.
2. 행동 결정: 테이블을 참조하여 Shift, Reduce, Accept 여부 판단함.
3. 스택 갱신: 규칙에 따라 기호를 삽입하거나 축약함.
4. 오류 처리: 문법에 어긋나는 토큰 발견 시 예외 메시지 송출함.
> 요약: 상태 전이와 스택 연산을 통해 논리적 구조를 완성함.

## Ⅳ. 문제점
- LL은 좌재귀 문법 처리가 불가하며, LR은 테이블 크기가 매우 큼.

## Ⅴ. 개선방안
- 단기: 좌재귀를 제거하거나 문법을 개조하여 파싱 가능하게 함.
- 중기: LALR 파서를 사용하여 SLR보다 강력하고 정형화된 처리를 수행함.
- 장기: GLR 파서 등을 도입하여 비결정적 문법까지 처리 범위를 확장함.

## Ⅵ. 전망
- 비결정적 문법 처리를 위한 GLR/Earley 알고리즘의 최적화가 핵심이며, 향후 자연어와 프로그래밍 언어 간의 경계를 허무는 인공지능 기반 코드 생성 및 실시간 문법 검사 엔진의 중추적 기능을 수행할 전망임.
- 클라우드 네이티브 환경에서의 마이크로서비스 간 인터페이스(IDL) 분석 및 자동 변환 도구의 핵심 로직으로 활용 가치가 지속 확대될 것임.
