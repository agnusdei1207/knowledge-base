# 074. 파싱 기법 — LL·LR 파서 (Parsing LL LR)

## Ⅰ. 개요

- **정의/개념**: 소스 코드의 토큰(Token) 열을 입력받아 해당 언어의 문법 규칙에 맞는지 검사하고, 문장의 계층적 구조를 나타내는 파스 트리(Parse Tree)나 추상 구문 트리(AST)를 생성하는 과정임
- **배경/필요성**: 어휘 분석 단계를 거친 단순한 토큰의 나열은 프로그램의 논리적 구조(제어문, 함수 정의 등)를 나타내지 못하므로, 이를 컴퓨터가 해석 가능한 트리 구조로 재구성하는 정밀한 구문 분석 알고리즘이 필요함

## Ⅱ. 특징 및 비교 (Top-down vs Bottom-up)

| 판단 기준 | LL 파서 (Top-down) | LR 파서 (Bottom-up) |
|:---|:---|:---|
| **분석 방향** | 시작 기호에서 단말 기호로 (Top-down) | 단말 기호에서 시작 기호로 (Bottom-up) |
| **유도 방식** | 좌단 유도 (Leftmost Derivation) | 우단 유도 역순 (Rightmost Derivation) |
| **구현 난이도** | 낮음 (재귀 하향 방식 가능) | 높음 (파싱 테이블 및 스택 활용) |
| **문법 범위** | 좁음 (좌재귀 제거 등 제약) | 넓음 (대부분의 CFG 처리 가능) |
| **오류 탐지** | 즉각적이고 이해하기 쉬운 메시지 | 탐지 위치 파악이 상대적으로 어려움 |

> 요약: LL은 단순하고 직관적인 구현에, LR은 복잡하고 강력한 문법 처리에 유리함

## Ⅲ. 구성요소/구조

- **구성요소**:
  - **Parsing Table**: 현재 상태와 입력 토큰을 바탕으로 수행할 동작(Shift, Reduce, Accept, Error)을 정의한 표임
  - **Parsing Stack**: 현재 분석 중인 문법 기호와 상태 정보를 저장하는 메모리 공간임
  - **Lookahead**: 다음 동작을 결정하기 위해 미리 훑어보는 토큰의 개수(LL(1), LR(1) 등)임
  - **Shift**: 입력 토큰을 스택에 쌓는 동작(LR)임
  - **Reduce**: 스택 상단의 토큰들을 문법 규칙의 왼쪽 변(Non-terminal)으로 치환하는 동작(LR)임

- **파싱 프로세스 흐름도**:
```text
[Input Tokens] -> [Lookahead] -> [Parser Control] <-> [Parsing Table]
                                      |
                               [Parsing Stack]
                                      |
                                [Output Tree]
```

## Ⅳ. 문제점 및 개선방안

1. **[좌재귀(Left Recursion) 문제 (LL)]**: $A \to A \alpha$와 같은 규칙이 있을 때 무한 루프에 빠져 파싱이 불가능해짐
   - **개선방안**: 문법을 재작성하여 좌재귀를 우재귀로 변환하거나, LR 파싱 기법을 도입함 (확인: 파싱 종료 보장)
2. **[Shift-Reduce 충돌 (LR)]**: 다음 동작이 Shift인지 Reduce인지 결정할 수 없는 모호한 상황이 발생함
   - **개선방안**: 연산자 우선순위와 결합 법칙을 파싱 테이블 생성 시 명시하거나 문법을 비모호하게 수정함 (확인: 충돌 없는 테이블 생성)
3. **[오류 복구(Error Recovery)의 어려움]**: 구문 오류 발견 시 분석을 중단하지 않고 다음 토큰부터 재개하는 로직 구현이 복잡함
   - **개선방안**: Panic Mode(특정 구분자까지 토큰 스킵)나 에러 토큰 삽입/삭제 전략을 사용하여 사용자에게 한꺼번에 여러 오류를 보고함 (확인: 오류 복구 안정성)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **수식 계산기/DSL** | 구현이 쉬운 Recursive Descent(LL 계열) 파서로 간단한 산술식 처리 | 개발 소요 시간, 확장성 |
| **프로그래밍 언어 (C, Java)** | Yacc, Bison, ANTLR 등 Parser Generator를 사용해 LR/LALR 기반의 정교한 파서 구축 | 문법 커버리지, 파싱 속도 |
| **JSON/XML 파서** | 표준 규격에 맞춘 고속 파싱 엔진으로 데이터 직렬화/역직렬화 수행 | 메모리 점유율, 초당 처리 건수 |

> 요약: 실무에서는 손으로 직접 짜는 LL 파서와 도구를 사용하는 LR 파서가 목적에 맞게 혼용됨

## Ⅵ. 결론

파싱 기법은 컴퓨터 과학의 컴파일러 이론을 지탱하는 가장 고전적이면서도 정교한 알고리즘의 집합체임. 단순한 규칙 기반의 LL 방식부터 강력한 표현력을 가진 LR 방식까지, 각각의 특성을 이해하는 것은 견고한 소프트웨어의 입력 처리 체계를 설계하는 핵심 역량임. 최근에는 실시간 구문 강조(Syntax Highlighting)나 IDE의 코드 분석 도구에서 점진적 파싱(Incremental Parsing) 기술로 더욱 고도화되고 있음.
