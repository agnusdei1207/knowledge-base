# 📖 【암기용】 개념 완전 이해

> 목적: 근사 알고리즘을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 근사 알고리즘은 최적해 계산이 어려운 문제에서 보장된 오차 범위 안의 해를 다항시간에 구하는 방법임
- **왜 필요한가**: TSP, Vertex Cover, Set Cover 같은 NP-난해 문제는 입력이 커지면 최적해 탐색 비용이 급증한다. 업무는 제한시간 안에 쓸 수 있는 해와 품질 보증이 필요함.
- **핵심 직관**: 100점짜리 답을 며칠 뒤 받는 대신 95점 이상 답을 1분 안에 받되, 그 95점이라는 하한을 수학적으로 증명하는 접근임.

## 깊이 이해
- **배경·문제의식**: 완전탐색은 최적해를 보장하지만 후보 수가 기하급수적으로 증가한다. 근사 알고리즘은 최적해 대비 비율을 보장해 계산 시간과 해 품질의 균형을 맞춤.
- **작동 원리**: 최소화 문제는 `ALG <= alpha * OPT`, 최대화 문제는 `ALG >= OPT / alpha` 형태로 근사비를 제시함. Greedy, LP relaxation, primal-dual, local search가 대표 기법임.
- **비유**: 배송 경로를 완전탐색하면 모든 순서를 비교하지만, 근사 알고리즘은 가까운 군집을 먼저 묶고 최적해 대비 길이 상한을 보장하는 방식임.
- **구체 예시**: Vertex Cover는 임의 간선을 고르고 양끝 정점을 선택하는 방식으로 2-approx를 달성함.
- **흔한 오해·주의점**: 휴리스틱은 경험적 방법이고 근사 알고리즘은 근사비 증명을 포함한다. "대충 구함"이 아니라 품질 하한을 명시하는 알고리즘임.

## 연결 개념
- P vs NP — 최적해 계산이 어려운 문제군을 판단하는 배경
- 선형계획 완화 — 정수 제약을 완화해 근사해를 만드는 대표 기법
- 탐욕 알고리즘 — 근사 알고리즘의 구현 기초가 되는 선택 전략

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 근사 알고리즘은 NP-난해 최적화 문제에서 최적해 대비 보장 비율(alpha)을 갖는 해를 다항시간에 산출하는 방법임.
> 2. **가치**: 제한시간, 대규모 입력, 운영 SLA가 있는 환경에서 최적해 대신 검증 가능한 품질의 해를 제공함.
> 3. **판단 포인트**: 근사비, 시간복잡도, 입력 구조, 최적해 lower bound, 업무 허용오차를 함께 제시해야 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 최적해 대신 보장된 오차 범위 안의 해를 다항시간에 계산하는 알고리즘
- 배경: NP-난해 문제는 최적해 탐색 비용이 O(2^n) 또는 O(n!)로 커질 수 있어 제한시간 내 의사결정이 어려움
- 필요성: 근사비와 실행시간을 함께 제시해 이론과 실무 판단을 연결해야 함

---

## Ⅱ. 구조 및 구성요소

```text
최적화 문제 -> 완화/탐욕 선택 -> 근사해 생성 -> 근사비 증명 -> 운영 지표 확인
                  / LP relaxation
                  / greedy
                  / local search
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 목적함수 | 최소화·최대화 대상 수식화 | 비용, 거리, 지연, 수익 등 |
| 제약조건 | 해가 만족해야 할 조건 지정 | 용량, 시간창, 배정 제약 |
| 근사 기법 | 다항시간 해 생성 | Greedy, LP rounding, primal-dual |
| 근사비 | 최적해 대비 품질 보증 | 2-approx, ln n-approx, PTAS |

> 요약: 근사 알고리즘은 문제 모델링, 해 생성 기법, 근사비 증명, 운영 지표를 하나의 판단 구조로 묶음.

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 모델링 -> 최적해 하한/상한 계산 -> 근사해 생성 -> 근사비 분석 -> 제한시간 내 결과 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목적함수와 제약조건 모델링 | feasible 해 존재 여부 |
| 2 | relaxation 또는 greedy 기준 설정 | lower/upper bound 계산 |
| 3 | 근사해 산출 | 시간복잡도 O(n^k) 이하 |
| 4 | 근사비·gap 검증 | ALG/OPT 또는 gap % 측정 |

> 요약: 근사해는 모델링, 경계값 계산, 해 생성, 근사비 검증 순서로 산출되며 품질을 수치로 설명함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 최적해 탐색 대비 실행시간을 다항식으로 제한 | O(n log n), O(n^2) 등 명시 |
| 한계 | 모든 NP-난해 문제가 일정 근사비를 갖지는 않음 | APX-hard, inapproximability 확인 |
| 비교 대상 | 휴리스틱은 경험적, 근사는 증명 기반 | 근사비 alpha와 benchmark gap 구분 |
| 대표 사례 | Vertex Cover 2-approx, Set Cover ln n-approx | 업무 허용오차가 근사비보다 큰지 확인 |

> 요약: 근사 알고리즘은 시간 제한과 품질 보증을 동시에 제공하지만, 문제별 근사 가능성과 업무 허용오차를 확인해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 완전탐색·정확 알고리즘 | 근사비 보장 해 생성 | n이 크고 최적해 불필요하면 근사 선택 |
| 비용/성능 | O(2^n), O(n!) 가능 | O(n^k) 목표 | 제한시간 1분 이하 요구 시 근사 우선 |
| 운영/위험 | 휴리스틱 품질 편차 | 근사비·gap 지표 관리 | SLA에 허용오차 5~10% 명시 |

> 요약: 입력 규모가 크고 허용오차가 존재하면 정확해보다 근사비가 증명된 알고리즘을 우선 검토함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 품질 미달 | 업무 손실함수와 근사비 불일치 | 비용함수 재설계, gap 기준 설정 | 최적해 대비 gap %, 손실액 |
| 적용 불가 | 문제 구조가 근사 어려움 | FPT, branch and bound, Solver 병행 | timeout 비율, 최적성 gap |
| 데이터 편향 | benchmark와 운영 데이터 차이 | 운영 샘플 재평가, A/B 비교 | p95 실행시간, 실패 케이스 수 |

> 요약: 근사 알고리즘은 근사비만으로 충분하지 않으며 업무 손실, 적용 가능성, 데이터 분포를 함께 검증해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 해 품질 | gap 5% 이하 또는 근사비 alpha 명시 | optimal bound, benchmark |
| 실행시간 | p95 제한시간 이하 | 알고리즘 로그, 부하 테스트 |
| 모델 적합성 | 제약 위반 0건, infeasible 원인 기록 | 검증 데이터, 제약 감사 |

> 요약: 도입 후 성공 여부는 해 품질, 실행시간, 제약 준수율로 판단해야 함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 문제 판정: NP-난해 여부, 입력 크기 n, 최적해 필요 여부를 확인하고 정확 알고리즘 실행 가능 한계를 산정함.
2. 알고리즘 선택: Vertex Cover는 2-approx, Set Cover는 ln n-approx, 경로 문제는 metric 조건 충족 여부를 기준으로 선택함.
3. 운영 검증: gap %, p95 실행시간, 제약 위반 건수를 대시보드로 관리하고 기준 초과 시 Solver fallback을 수행함.

**결론 (2줄):**
- 기술사 판단: 최적성이 법적·정산 기준이면 정확해를 유지하고, 의사결정 시간이 핵심이면 근사비와 gap 기준을 명시한 근사 알고리즘이 타당함.
- 향후 방향: 근사 알고리즘은 ILP Solver, ML 예측, 온라인 알고리즘과 결합해 대규모 최적화의 기준 해법으로 확장됨.
