## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 소스 코딩은 데이터의 잉여도를 줄여 압축하는 과정이며, 채널 코딩은 잉여도를 고의로 추가하여 오류를 제어하는 통신 시스템의 핵심 과정임 |
| 배경/필요성 | 대역폭을 절약(소스 코딩)하면서 동시에 전송 중 발생하는 잡음으로부터 데이터 신뢰성을 보장(채널 코딩)하기 위해 상호 보완적으로 필요함 |
| 출제 의도 | 섀넌의 분리 정리(Separation Theorem)에 기반한 통신 모델에서 두 코딩 기법의 목적과 메커니즘 차이 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|  Original Data    | ----> | Source Coding     | ----> | Channel Coding    |
|  (Raw info)       |       | (Compression)     |       | (Error Protection)|
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 원본 데이터 | 압축이나 오류 방지 처리가 되지 않은 초기 정보 | 포장 전 물건 |
| 소스 코딩 | 불필요한 중복(Redundancy)을 제거하여 데이터를 압축 (허프만 등) | 진공 포장 (부피 최소화) |
| 채널 코딩 | 오류 검출 및 정정을 위해 의도적 잉여(Redundancy) 비트를 부가 (해밍 등) | 뽁뽁이 완충재 (파손 방지) |
> 요약: 소스 코딩은 데이터 크기를 줄이는 '압축'을, 채널 코딩은 신뢰성을 높이는 '오류 제어'를 담당함

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 소스 압축   | -> | 2. 잉여 비트   | -> | 3. 채널 전송   | -> | 4. 복호화/해제 |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 소스 압축: 송신 측에서 허프만 코딩이나 LZW 등을 사용해 원본 데이터를 최소 비트로 무손실/손실 압축함
2. 잉여 비트: 압축된 데이터 스트림에 패리티, CRC 등 채널 코딩을 적용하여 복구용 잉여 비트를 삽입함
3. 채널 전송: 잡음이 존재하는 물리적 매체(무선, 케이블 등)를 통해 인코딩된 스트림을 전송함
4. 복호화/해제: 수신 측에서 채널 코딩의 잉여 비트를 이용해 오류를 정정한 후, 소스 코딩을 해제하여 원본을 복원함
> 요약: 송신 시 [압축 -> 안전 포장]을 거쳐 전송하고, 수신 시 [오류 정정 -> 압축 해제]로 복구함

## Ⅳ. 문제점
- 상충 관계(Trade-off): 소스 코딩으로 극도로 압축된 데이터는 1비트의 오류에도 전체 파일이 손상되는 '오류 전파(Error Propagation)'에 매우 취약해짐
- 시스템 지연 증가: 강력한 압축과 복잡한 오류 정정(LDPC 등)을 통과하는 인코딩/디코딩 과정에서 연산 시간이 길어져 실시간 통신에 제약이 됨

## Ⅴ. 개선방안
- 결합 소스-채널 코딩(JSCC): 섀넌의 분리 정리 한계를 극복하기 위해, 멀티미디어 특성을 고려하여 중요한 정보에는 강력한 채널 코딩을 적용하는 등 두 단계를 통합 최적화함
- 하드웨어 가속: 복잡한 인코딩 및 디코딩 로직을 FPGA나 전용 DSP 칩으로 오프로딩하여 처리 지연을 최소화함

## Ⅵ. 전망
- 두 코딩의 분리는 이론적 근간으로 유지되나, AI 기반의 시맨틱 통신(Semantic Communication)으로 진화하면서 수신자가 의미만 정확히 파악하면 되는 형태의 새로운 통합 코딩 방식이 부상할 것임
