# 📖 【암기용】 개념 완전 이해

> 목적: 소스 코딩과 채널 코딩을 처음 보는 사람도 압축과 오류 정정 목적 차이를 이해하게 만든다.

## 한눈에
- **개요**: 소스 코딩은 중복을 줄이고, 채널 코딩은 오류 복구를 위해 중복을 추가하는 부호화
- **왜 필요한가**: 저장·전송 비용은 줄여야 하지만, 잡음 채널에서는 오류를 검출·정정할 여유 비트가 필요함
- **핵심 직관**: 짐을 보낼 때 부피는 압축하고, 파손 방지를 위해 완충재는 추가하는 관계임

## 깊이 이해
- **배경·문제의식**
  - 데이터 원본에는 통계적 중복이 있고, 통신·저장 채널에는 잡음과 비트 오류가 있음
  - 하나의 부호화로 압축과 오류 정정을 동시에 만족하기 어려움
- **작동 원리**
  - 소스 코딩은 엔트로피 하한에 가깝게 비트 수를 줄임
  - 채널 코딩은 부호율 R을 낮추고 패리티·검사 행렬을 추가해 BER을 목표 수준으로 낮춤
- **비유**: 이메일 첨부파일을 ZIP으로 줄인 뒤, 전송 중 손상 대비를 위해 체크섬·재전송·오류정정 코드를 붙이는 방식임.
- **구체 예시**: 1MB 로그를 허프만/LZ로 400KB로 줄인 후, 무선 전송에서는 LDPC 부호율 1/2를 적용해 800KB 상당 전송 비트를 만들 수 있음.
- **흔한 오해·주의점**
  - 채널 코딩은 크기를 줄이는 기술이 아님
  - 오류 정정을 위해 의도적으로 중복을 넣는 기술임

## 연결 개념
- 엔트로피 — 소스 코딩의 압축 하한
- 섀넌 채널 용량 — 채널 코딩의 전송 상한
- CRC·FEC·ARQ — 오류 검출·정정·재전송 전략

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 소스 코딩·채널 코딩 비교 답안 양식이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소스 코딩은 중복 제거, 채널 코딩은 오류 제어를 위한 중복 추가임.
> 2. **가치**: 저장·전송 비트 수 절감과 BER 목표 달성은 서로 다른 단계에서 분리 설계해야 함.
> 3. **판단 포인트**: 데이터 분포는 압축률, 채널 SNR은 부호율, 서비스 SLA는 오류 허용치를 결정함.

## Ⅰ. 개요 및 필요성

- 개요: 소스 코딩은 중복 제거, 채널 코딩은 오류 제어를 위한 중복 추가 부호화
- 배경: 소스 코딩은 정보원 중복을 제거해 비트 수를 줄이고, 채널 코딩은 잡음 채널의 오류를 제어하기 위해 중복 비트를 추가함
- 필요성: 저장·통신·멀티미디어 시스템은 두 단계를 분리해야 품질과 비용을 동시에 설계할 수 있음

## Ⅱ. 구조 및 구성요소

```text
Source -> Source Coding -> Channel Coding -> Channel
중복 제거 -> 오류정정 중복 추가 -> 전송/저장
```

| 구성요소 | 역할 | 대표 기술 |
|:---|:---|:---|
| 정보원 | 원본 데이터·확률 분포 제공 | 텍스트, 영상, 센서 |
| 소스 코딩 | 통계적 중복 제거 | Huffman, Arithmetic, LZ, RLE |
| 채널 코딩 | 오류 검출·정정 비트 추가 | Hamming, Reed-Solomon, LDPC, Polar |
| 채널 | 잡음·손실·왜곡 발생 | 무선, 저장장치, 네트워크 |

> 요약: 소스 코딩은 채널 이전에 비트를 줄이고, 채널 코딩은 전송 전 오류 정정 여유를 추가함.

## Ⅲ. 동작원리 및 흐름도

```text
원본 데이터 -> 압축(중복 제거) -> 오류정정 부호 추가
       -> 전송/저장 -> 오류정정 복호 -> 압축 복호 -> 원본 복원
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원본 통계 분석 | 엔트로피 H(X), 압축률 |
| 2 | 소스 코딩 수행 | 복원 후 원본 일치 |
| 3 | 채널 코딩 수행 | 부호율 R, 패리티 길이 |
| 4 | 수신·복호 | 목표 BER `10^-6`, CRC 통과 |

> 요약: 송신 측은 압축 후 오류정정 비트를 붙이고, 수신 측은 오류정정 후 압축을 해제해 원본을 복원함.

## Ⅳ. 특징

| 구분 | 소스 코딩 | 채널 코딩 | 수치 판단 |
|:---|:---|:---|:---|
| 목적 | 중복 제거·비트 수 절감 | 오류 검출·정정 | 압축률 vs BER |
| 이론 기준 | 엔트로피 `H(X)` | 채널 용량 `C` | `L≥H(X)`, `R≤C` |
| 비트 변화 | 원본보다 감소 | 패리티로 증가 | 부호율 1/2면 전송 비트 2배 |
| 대표 기술 | Huffman, LZ, RLE | Hamming, LDPC, Polar | 데이터 분포·SNR 기준 |

> 요약: 소스 코딩은 비트를 줄이고 채널 코딩은 비트를 늘리며, 각각 엔트로피와 채널 용량으로 한계를 판단함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 부호화 | 소스 코딩 후 채널 코딩 | 압축과 오류 제어를 분리할 때 |
| 비용/성능 | 무압축+FEC | 압축+FEC | 비트율과 BER 목표 동시 존재 |
| 운영/위험 | CRC만 적용 | FEC·CRC·ARQ 조합 | 지연 100ms, BER `10^-6` 요구 |

> 요약: 저장·전송 시스템은 소스 코딩으로 비트 수를 줄이고 채널 코딩으로 오류율을 낮추는 순차 구조가 기본임

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오류 증폭 | 압축 비트 손상 시 복호 실패 | FEC 후 CRC, interleaving | 복호 실패율 |
| 지연 증가 | 강한 FEC·재전송 | 경량 FEC+ARQ 혼합 | end-to-end 지연 p95 |
| 압축률 저하 | 암호화·난수 데이터 | 압축 생략, 원본 플래그 | 압축률 1.0 미만 |

> 요약: 부호화 계층 리스크는 오류 증폭, 지연, 압축률 저하이며 복호 실패율과 p95 지연으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 압축률 | 원본 대비 비트율 감소 | 샘플 데이터 압축 |
| 오류율 | BER `10^-6` 이하 | 채널 시뮬레이션 |
| 지연 | 실시간 서비스 p95 100ms 이하 | APM·패킷 트레이스 |

> 요약: 소스·채널 코딩 성공은 압축률, BER, 지연 목표 동시 충족으로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 저장 시스템은 LZ4/Zstd 등 소스 코딩 후 CRC32C로 무결성 검출, 복구는 복제·Erasure Coding으로 분리
2. 무선 전송은 영상 코덱으로 비트율을 낮춘 뒤 LDPC·Polar 부호로 목표 BER `10^-6` 수준 제어
3. 실시간 서비스는 지연 100ms 이하 요구 시 강한 FEC보다 경량 FEC+ARQ 혼합으로 재전송 비용 조절

**결론 (2줄):**
- 기술사 판단: 비용 문제가 핵심이면 소스 코딩, 오류율 문제가 핵심이면 채널 코딩, 무선·저장 시스템은 두 단계를 순차 적용함.
- 향후 방향: 5G/6G·분산 저장은 압축, FEC, 무결성 검증을 계층화해 전송률과 오류율을 함께 관리함.
