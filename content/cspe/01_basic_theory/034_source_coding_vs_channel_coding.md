## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소스 코딩(Source Coding)은 데이터에서 **중복을 제거하여 크기를 줄이는** 압축 기술이고, 채널 코딩(Channel Coding)은 **의도적으로 중복을 추가하여 전송 오류를 검출·정정**하는 기술이다. 두 기술은 목적이 정반대(중복 제거 vs 중복 추가)이지만, 통신 시스템에서 **직렬로 결합**되어 동작한다.
> 2. **가치**: Shannon의 분리 정리(Separation Theorem)에 의해, 소스 코딩과 채널 코딩을 독립적으로 최적화해도 전체 최적에 도달할 수 있다. 이 분리 원칙이 현대 통신 시스템(5G, WiFi, 위성) 설계의 기반이다.
> 3. **융합**: 모바일 통신(LTE/5G: Turbo/LDPC + H.265), 저장장치(SSD: LDPC + LZ4), 방송(DVB: RS+Viterbi + MPEG), 인터넷(HTTPS: TLS + gzip) 등 모든 디지털 통신·저장에서 두 코딩이 쌍으로 동작한다.

## Ⅰ. 개요 및 필요성

- **개념**: 통신 시스템의 데이터 처리 파이프라인은 `소스 → 소스 인코딩 → 채널 인코딩 → 변조 → 채널(잡음) → 복조 → 채널 디코딩 → 소스 디코딩 → 수신`이다. 소스 인코딩은 데이터를 최소 비트로 압축하고, 채널 인코딩은 잡음에 대비해 오류 정정 코드를 추가한다.

- **필요성**: 소스 코딩 없이 전송하면 대역폭을 낭비하고, 채널 코딩 없이 전송하면 잡음으로 데이터가 손상된다. 두 기술의 조합이 "적은 대역폭으로 오류 없이 전송"을 가능하게 한다.

- **비유**: 소스 코딩은 **짐을 최소 크기로 압축 포장하기**, 채널 코딩은 **깨질 수 있는 짐에 뽁뽁이(완충재)를 감싸기**이다. 압축(소스)으로 택배 상자 크기를 줄이고, 완충재(채널)로 운송 중 파손을 방지한다.

```text
+-----------------------------------------------------------------------+
|        통신 시스템의 데이터 처리 파이프라인                            |
+-----------------------------------------------------------------------+
|                                                                       |
|  [송신측]                                                             |
|  원본 데이터                                                          |
|    |                                                                  |
|    v                                                                  |
|  [소스 인코딩] — 중복 제거 (압축)                                    |
|  허프만, LZW, H.265 등                                               |
|    |                                                                  |
|    v                                                                  |
|  [채널 인코딩] — 중복 추가 (오류 정정)                               |
|  해밍, RS, LDPC, Turbo 등                                            |
|    |                                                                  |
|    v                                                                  |
|  [변조 → 채널(잡음) → 복조]                                         |
|    |                                                                  |
|    v                                                                  |
|  [수신측]                                                             |
|  [채널 디코딩] — 오류 검출·정정                                      |
|    |                                                                  |
|    v                                                                  |
|  [소스 디코딩] — 압축 해제                                           |
|    |                                                                  |
|    v                                                                  |
|  복원 데이터                                                          |
|                                                                       |
|  ★ 소스 코딩으로 크기를 줄이고, 채널 코딩으로 보호를 추가            |
|  ★ 순서가 중요: 먼저 압축, 그 다음 오류 정정 추가                   |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 통신 시스템의 전체 파이프라인을 보여준다. 소스 인코딩이 먼저 실행되어 데이터를 최소 크기로 줄이고, 채널 인코딩이 그 위에 오류 정정 코드를 추가한다. 수신측에서는 역순으로 채널 디코딩(오류 정정) → 소스 디코딩(압축 해제)을 수행한다. 소스 코딩을 먼저 하는 이유는 이미 압축된 데이터(높은 엔트로피)에 채널 코딩을 추가하는 것이 효율적이기 때문이다.

- **📢 섹션 요약 비유**: 택배 보내기에서 "짐 압축(소스) → 뽁뽁이 포장(채널) → 택배 발송 → 뽁뽁이 해제(채널) → 짐 꺼내기(소스)"의 순서입니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 소스 코딩 | 채널 코딩 |
|:---|:---|:---|
| **목적** | 중복 제거 → 크기 최소화 | 중복 추가 → 오류 내성 |
| **이론적 한계** | 엔트로피 H (하한) | 채널 용량 C (상한) |
| **방향** | 비트 수 감소 | 비트 수 증가 |
| **대표 알고리즘** | 허프만, LZW, H.265, AAC | 해밍, RS, LDPC, Polar |
| **손실 허용** | 무손실 or 손실(이미지·음성) | 무손실 (정확 복원 필수) |

### 분리 정리 — 독립 최적화의 수학적 근거

- Shannon의 분리 정리: 소스 코딩과 채널 코딩을 **분리하여 각각 최적화**해도 전체 시스템의 최적 성능에 도달할 수 있다(지연 무한대 가정). 이 덕분에 압축 알고리즘(JPEG, H.265)과 오류 정정 알고리즘(LDPC, Polar)을 독립적으로 개발하고 조합할 수 있다.

- **예외**: 실시간 통신처럼 지연 제약이 있으면 **공동 소스-채널 코딩(Joint Source-Channel Coding)**이 분리 방식보다 유리할 수 있다. 딥러닝 기반 JSCC가 연구되고 있다.

- **📢 섹션 요약 비유**: 분리 정리는 "짐 압축 전문가와 포장 전문가를 따로 고용해도, 한 명이 둘 다 하는 것만큼 잘 된다"는 것입니다.

## Ⅲ. 비교 및 연결

### 비교 1: 소스 코딩 vs 채널 코딩 종합 비교

| 비교 항목 | 소스 코딩 (압축) | 채널 코딩 (오류 정정) |
|:---|:---|:---|
| **정보 중복** | 제거 (엔트로피까지) | 추가 (의도적 중복) |
| **데이터 크기** | 줄어듦 | 늘어남 |
| **이론적 한계** | H(X) — 소스 엔트로피 | C — 채널 용량 |
| **실패 시** | 파일이 큼 (비효율) | 데이터 손상 (치명적) |
| **손실 허용** | 가능 (JPEG, MP3) | 불가 (정확 복원 필수) |
| **실행 순서** | 먼저 (송신측) | 나중 (송신측) |
| **대표 표준** | H.265, AAC, gzip | LDPC, Polar, RS |

### 과목 융합 관점
- **5G NR**: H.265(소스) + LDPC/Polar(채널) 조합. 4K 동영상을 H.265로 압축 후 LDPC로 보호하여 전송한다.
- **SSD**: LZ4(소스, 컨트롤러 내부 압축) + LDPC(채널, NAND 오류 정정) 조합.
- **웹**: gzip(소스, HTTP 압축) + TLS(암호화) + TCP(재전송=채널 코딩의 ARQ 방식) 조합.

- **📢 섹션 요약 비유**: 5G 동영상 스트리밍은 "짐 압축(H.265) → 뽁뽁이(LDPC) → 택배(전파) → 뽁뽁이 해제 → 짐 꺼내기"의 연속입니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — 위성 통신**: 심우주 탐사선(보이저)은 신호가 극히 약하므로 강력한 채널 코딩(컨볼루션 코드 + RS 코드)이 필수이다. 소스 코딩으로 데이터를 최소화하고, 채널 코딩으로 10⁻⁶ BER 미만을 달성한다.

2. **시나리오 — 실시간 화상회의**: WebRTC는 VP9/AV1(소스, 손실 압축)으로 영상을 압축하고, NACK/FEC(채널, 선택적 ARQ + 전방 오류 정정)로 패킷 손실에 대응한다. 지연 제약 때문에 재전송(ARQ)보다 FEC를 선호한다.

### 안티패턴
- **채널 코딩 후 소스 코딩**: 채널 코딩이 추가한 중복을 소스 코딩이 다시 제거하면 오류 정정 능력이 사라진다. 반드시 소스 → 채널 순서를 지킨다.
- **암호화 후 압축**: 암호화된 데이터는 엔트로피가 최대이므로 압축이 불가능하다. 반드시 압축 → 암호화 순서.

- **📢 섹션 요약 비유**: "뽁뽁이(채널 코딩) 감싼 다음에 압축하면, 뽁뽁이가 찌그러져서 보호 기능을 잃습니다."

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 코딩 없이 전송 | 소스+채널 코딩 적용 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | 4K 원본 12Gbps | H.265+LDPC → 50Mbps | **240배** 대역폭 절감 |
| **정량** | BER 10⁻² (잡음 채널) | LDPC 적용 → BER 10⁻⁶ | **10,000배** 오류 감소 |
| **정성** | "전송 불가능" | "오류 없이 효율적 전송" | 디지털 통신 실현 |

### 참고 표준
- **Shannon, C.E. (1948)**: 소스/채널 코딩 정리 + 분리 정리
- **3GPP TS 38.212**: 5G NR 채널 코딩 (LDPC + Polar)
- **ITU-T H.265**: HEVC 동영상 소스 코딩

소스 코딩과 채널 코딩은 디지털 통신의 "양 날개"이다. 하나는 데이터를 최소화하고, 다른 하나는 데이터를 보호한다. 두 기술의 분리 설계가 현대 통신 시스템의 모듈화와 표준화를 가능하게 했다.

### 👶 어린이를 위한 3줄 비유 설명

1. 소스 코딩은 "짐을 작게 압축하기"예요. 큰 이불을 압축팩에 넣으면 반으로 줄어들어요!
2. 채널 코딩은 "깨지기 쉬운 짐에 뽁뽁이 감싸기"예요. 택배 중에 부딪혀도 안 깨져요!
3. 먼저 압축하고(작게!), 그 다음 뽁뽁이를 감싸야(보호!) 해요. 순서가 반대면 뽁뽁이가 찌그러져요!
