# 📖 【암기용】 개념 완전 이해

> 목적: 소스 코딩과 채널 코딩을 처음 보는 사람도 압축과 오류 정정 목적 차이를 이해하게 만든다.

## 한눈에
- **개요**: 소스 코딩과 채널 코딩은 **정보이론(Information Theory)**에서 데이터를 **부호화(Encoding)**하는 두 개의 반대 방향 기법이다. 소스 코딩은 중복을 **제거**해 비트 수를 줄이고, 채널 코딩은 오류 복구를 위해 중복을 **추가**한다.
- **왜 필요한가**: 저장·전송 비용은 줄여야 하지만(압축), 잡음이 있는 통신 채널에서는 비트가 깨질 수 있으므로 오류를 검출·정정할 여유 비트가 있어야 한다(오류 정정). 두 요구가 정반대라서 별도의 단계로 분리해서 설계한다.
- **핵심 직관**: 택배를 보낼 때 부피는 최대한 압축 포장하고(소스 코딩), 파손 방지를 위해 완충재는 오히려 추가하는 것(채널 코딩)과 같다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 정보이론 (Information Theory) | 정보의 압축 한계와 전송 한계를 수학적으로 다루는 상위 학문 — 소스·채널 코딩이 모두 이 안에 속함 | 정보를 "양"으로 재는 물리학 |
| 엔트로피 H(X) | 정보원이 가진 불확실성(평균 정보량)의 크기 — 소스 코딩이 줄일 수 있는 압축의 이론적 하한 | 예측 불가능할수록 큰 값 (동전 던지기보다 로또가 큼) |
| 소스 코딩 (Source Coding) | 정보원의 통계적 중복을 제거해 표현 비트 수를 줄이는 부호화 | 문장에서 군더더기를 빼고 요약하는 것 |
| 채널 코딩 (Channel Coding) | 잡음 채널에서 오류를 검출·정정하기 위해 의도적으로 중복 비트를 추가하는 부호화 | 중요한 말을 두 번 반복해서 말하는 것 |
| 부호율 R (Code Rate) | 채널 코딩 후 전체 비트 중 실제 정보 비트가 차지하는 비율 (정보비트/전체비트) | R=1/2면 원본 1비트를 보내려고 2비트를 씀 |
| 패리티 비트 (Parity Bit)·검사 행렬 | 오류 검출·정정을 위해 덧붙이는 추가 비트, 그 규칙을 정의한 행렬 | 원본 옆에 붙이는 "검산 숫자" |
| BER (Bit Error Rate) | 전송된 비트 중 오류가 발생한 비트의 비율 | 100만 비트 중 1비트가 틀리면 BER=10⁻⁶ |
| 섀넌 채널 용량 C (Shannon Capacity) | 주어진 채널에서 오류 없이 보낼 수 있는 전송률의 이론적 상한 | 도로가 감당 가능한 차량 대수의 한계 |
| 대표 소스 코딩 기법 | Huffman, 산술 부호화(Arithmetic), LZ 계열, RLE | 압축 프로그램(zip 등)의 내부 알고리즘 |
| 대표 채널 코딩 기법 | Hamming, Reed-Solomon, LDPC, Polar | 통신 규격(5G, Wi-Fi)에 들어가는 오류정정 부호 |
| CRC / FEC / ARQ | 오류 검출(CRC), 전방 오류 정정(FEC), 재전송 요청(ARQ) — 오류 대응 3대 전략 | 검산(CRC), 스스로 고침(FEC), 다시 보내달라 요청(ARQ) |

## 깊이 이해

### 왜 두 코딩을 분리하나 (배경·문제의식)
- 정보원(데이터)에는 통계적 중복이 있다. 예를 들어 알파벳 'e'는 'z'보다 훨씬 자주 등장하므로, 자주 나오는 문자에 짧은 부호를 주고 드문 문자에 긴 부호를 주면 평균 비트 수를 줄일 수 있다 — 이것이 소스 코딩(예: 허프만 코딩)이다.
- 반면 통신·저장 채널에는 물리적 잡음(전자기 간섭, 저장매체 결함)이 있어 비트가 뒤집힐 수 있다. 압축된 데이터는 중복이 이미 다 빠져 있어 비트 하나만 깨져도 복원이 불가능해진다 — 그래서 전송 직전에 일부러 중복(패리티)을 다시 넣어 오류를 잡아내는 채널 코딩이 필요하다.
- 섀넌의 분리 정리(Separation Theorem)에 따르면, 소스 코딩과 채널 코딩을 독립적으로 최적화해서 순서대로 적용해도 이론적으로 성능 손실이 없다. 그래서 실제 시스템은 압축(소스 코딩) → 오류정정 부호 추가(채널 코딩) 순서로 파이프라인을 구성한다.

### 소스 코딩을 수치로 이해하기 (엔트로피)
- 어떤 정보원이 심볼 A(확률 0.5), B(확률 0.25), C(확률 0.25) 세 가지만 낸다고 하자. 엔트로피 H(X) = -Σp(x)log₂p(x) = -(0.5·log₂0.5 + 0.25·log₂0.25 + 0.25·log₂0.25) = 0.5×1 + 0.25×2 + 0.25×2 = 1.5비트.
- 이는 "이 정보원 심볼 1개를 표현하는 데 평균 1.5비트면 충분하다"는 압축의 이론적 하한이다. A/B/C를 각각 2비트(00/01/10)로 고정 배정하면 평균 2비트가 필요하지만, 허프만 코딩으로 A에 1비트(0), B와 C에 2비트(10, 11)를 배정하면 평균 부호 길이가 0.5×1+0.25×2+0.25×2=1.5비트로 엔트로피 하한에 정확히 도달한다.

### 채널 코딩을 수치로 이해하기 (부호율과 BER)
- 가장 단순한 채널 코딩은 반복 부호(Repetition Code)다. 원본 1비트를 3번 반복해서 보내면(예: 1 → 111) 부호율 R = 1/3이다. 수신 측에서 3비트 중 다수결로 원래 값을 복원하면 1비트만 뒤집힌 오류를 정정할 수 있다.
- Hamming(7,4) 코드는 정보 비트 4개에 패리티 비트 3개를 더해 총 7비트를 보낸다. 부호율 R = 4/7 ≈ 0.571이며, 1비트 오류를 정정할 수 있다.
- 1MB(약 800만 비트)의 로그 데이터를 무선으로 보낼 때 LDPC 부호율 1/2를 적용하면, 실제 전송해야 할 비트 수는 약 2배인 1600만 비트(2MB 상당)로 늘어나지만, 그 대신 채널에서 발생하는 비트 오류를 수신 측이 스스로 정정해 목표 BER 10⁻⁶ 이하를 달성할 수 있다.

### 섀넌 채널 용량과 두 코딩의 방향 차이
- 섀넌의 채널 용량 정리는 "부호율 R이 채널 용량 C보다 작으면(R < C), 오류 확률을 원하는 만큼 0에 가깝게 낮추는 부호가 반드시 존재한다"는 것을 보장한다. 즉 채널 코딩의 목표는 R ≤ C를 만족하는 부호를 찾는 것이다.
- 반대로 소스 코딩의 목표는 평균 부호 길이 L ≥ H(X)를 만족하면서 최대한 H(X)에 근접하는 것이다. 두 부등식의 방향이 정반대인 것이 두 코딩의 본질적 차이를 보여준다 — 압축은 하한(H(X))에 다가가려 하고, 오류정정은 상한(C) 아래에 머물려 한다.

### 비유와 흔한 오해
- **비유**: 이메일 첨부파일을 ZIP으로 압축(소스 코딩)한 뒤, 전송 도중 손상에 대비해 체크섬과 재전송 로직(채널 코딩)을 붙이는 것과 같다. 압축은 파일을 작게 만들지만, 오류정정 준비는 오히려 통신 계층에서 비트 수를 늘린다.
- **오해**: 채널 코딩을 "압축을 더 세게 하는 기술"로 착각하면 안 된다. 채널 코딩은 크기를 줄이는 게 아니라 의도적으로 비트를 더 보내 오류를 견디게 만드는 기술이다. 압축률을 높이는 소스 코딩과는 목적이 정반대다.

## 연결 개념
- 엔트로피 — 소스 코딩이 도달할 수 있는 압축의 이론적 하한
- 섀넌 채널 용량 — 채널 코딩이 지켜야 할 전송률의 이론적 상한
- CRC·FEC·ARQ — 오류를 검출(CRC)하고, 스스로 정정(FEC)하거나 재전송(ARQ)을 요청하는 실전 오류 대응 전략
- 런랭스 인코딩(RLE)·허프만 코딩 (033) — 소스 코딩의 대표 구현 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 소스 코딩·채널 코딩 비교 답안 양식이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소스 코딩은 중복 제거, 채널 코딩은 오류 제어를 위한 중복 추가임.
> 2. **가치**: 저장·전송 비트 수 절감과 BER 목표 달성은 서로 다른 단계에서 분리 설계해야 함.
> 3. **판단 포인트**: 데이터 분포는 압축률, 채널 SNR은 부호율, 서비스 SLA는 오류 허용치를 결정함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 코딩의 역할 구분 확인 | 소스=중복 제거(압축), 채널=중복 추가(오류 제어) — 방향이 반대 | 두 코딩을 모두 "압축 기술"로 묶는 오류 |
| 이론 한계 이해 확인 | 엔트로피(압축 하한)와 채널 용량(전송 상한, 섀넌) | 한계 정리 없이 기법 이름만 나열 |
| 분리 설계 판단 확인 | 분리 정리에 따라 압축률과 부호율을 독립 설계 | 압축을 높이면 오류도 줄어든다는 인과 오류 |

> 요약: 이 문제는 기법 나열이 아니라 중복을 빼는 단계와 넣는 단계의 분리 설계 원리를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 소스 코딩은 중복 제거, 채널 코딩은 오류 제어를 위한 중복 추가 부호화
- 배경: 소스 코딩은 정보원 중복을 제거해 비트 수를 줄이고, 채널 코딩은 잡음 채널의 오류를 제어하기 위해 중복 비트를 추가함
- 필요성: 저장·통신·멀티미디어 시스템은 두 단계를 분리해야 품질과 비용을 동시에 설계할 수 있음

## Ⅱ. 구조 및 구성요소

```text
Source -> Source Coding -> Channel Coding -> Channel
중복 제거 -> 오류정정 중복 추가 -> 전송/저장
```

| 구성요소 | 역할 | 대표 기술 |
|:---|:---|:---|
| 정보원 | 원본 데이터·확률 분포 제공 | 텍스트, 영상, 센서 |
| 소스 코딩 | 통계적 중복 제거 | Huffman, Arithmetic, LZ, RLE |
| 채널 코딩 | 오류 검출·정정 비트 추가 | Hamming, Reed-Solomon, LDPC, Polar |
| 채널 | 잡음·손실·왜곡 발생 | 무선, 저장장치, 네트워크 |

> 요약: 소스 코딩은 채널 이전에 비트를 줄이고, 채널 코딩은 전송 전 오류 정정 여유를 추가함.

## Ⅲ. 동작원리 및 흐름도

```text
원본 데이터 -> 압축(중복 제거) -> 오류정정 부호 추가
       -> 전송/저장 -> 오류정정 복호 -> 압축 복호 -> 원본 복원
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원본 통계 분석 | 엔트로피 H(X), 압축률 |
| 2 | 소스 코딩 수행 | 복원 후 원본 일치 |
| 3 | 채널 코딩 수행 | 부호율 R, 패리티 길이 |
| 4 | 수신·복호 | 목표 BER `10^-6`, CRC 통과 |

> 요약: 송신 측은 압축 후 오류정정 비트를 붙이고, 수신 측은 오류정정 후 압축을 해제해 원본을 복원함.

## Ⅳ. 특징

| 구분 | 소스 코딩 | 채널 코딩 | 수치 판단 |
|:---|:---|:---|:---|
| 목적 | 중복 제거·비트 수 절감 | 오류 검출·정정 | 압축률 vs BER |
| 이론 기준 | 엔트로피 `H(X)` | 채널 용량 `C` | `L≥H(X)`, `R≤C` |
| 비트 변화 | 원본보다 감소 | 패리티로 증가 | 부호율 1/2면 전송 비트 2배 |
| 대표 기술 | Huffman, LZ, RLE | Hamming, LDPC, Polar | 데이터 분포·SNR 기준 |

> 요약: 소스 코딩은 비트를 줄이고 채널 코딩은 비트를 늘리며, 각각 엔트로피와 채널 용량으로 한계를 판단함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 부호화 | 소스 코딩 후 채널 코딩 | 압축과 오류 제어를 분리할 때 |
| 비용/성능 | 무압축+FEC | 압축+FEC | 비트율과 BER 목표 동시 존재 |
| 운영/위험 | CRC만 적용 | FEC·CRC·ARQ 조합 | 지연 100ms, BER `10^-6` 요구 |

> 요약: 저장·전송 시스템은 소스 코딩으로 비트 수를 줄이고 채널 코딩으로 오류율을 낮추는 순차 구조가 기본임

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오류 증폭 | 압축 비트 손상 시 복호 실패 | FEC 후 CRC, interleaving | 복호 실패율 |
| 지연 증가 | 강한 FEC·재전송 | 경량 FEC+ARQ 혼합 | end-to-end 지연 p95 |
| 압축률 저하 | 암호화·난수 데이터 | 압축 생략, 원본 플래그 | 압축률 1.0 미만 |

> 요약: 부호화 계층 리스크는 오류 증폭, 지연, 압축률 저하이며 복호 실패율과 p95 지연으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 압축률 | 원본 대비 비트율 감소 | 샘플 데이터 압축 |
| 오류율 | BER `10^-6` 이하 | 채널 시뮬레이션 |
| 지연 | 실시간 서비스 p95 100ms 이하 | APM·패킷 트레이스 |

> 요약: 소스·채널 코딩 성공은 압축률, BER, 지연 목표 동시 충족으로 판단함

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 저장 시스템은 LZ4/Zstd 등 소스 코딩 후 CRC32C로 무결성 검출, 복구는 복제·Erasure Coding으로 분리
2. 무선 전송은 영상 코덱으로 비트율을 낮춘 뒤 LDPC·Polar 부호로 목표 BER `10^-6` 수준 제어
3. 실시간 서비스는 지연 100ms 이하 요구 시 강한 FEC보다 경량 FEC+ARQ 혼합으로 재전송 비용 조절

**결론 (2줄):**
- 기술사 판단: 비용 문제가 핵심이면 소스 코딩, 오류율 문제가 핵심이면 채널 코딩, 무선·저장 시스템은 두 단계를 순차 적용함.
- 향후 방향: 5G/6G·분산 저장은 압축, FEC, 무결성 검증을 계층화해 전송률과 오류율을 함께 관리함.
