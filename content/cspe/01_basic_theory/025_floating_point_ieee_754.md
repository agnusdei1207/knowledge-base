## Ⅰ. 개요
- **정의**: 실수를 부호·지수·가수 세 필드로 분할하여 이진 표현하는 국제 표준임
- **배경/필요성**: 정수만으로는 소수점 이하 값과 극대·극소 범위를 표현할 수 없으므로, 유한 비트로 넓은 수 범위를 근사하는 통일 규격이 필요함
- **비유**: 과학적 표기법 1.23 × 10^4 에서 부호·지수·유효숫자를 각각 별도 칸에 적는 것과 동일함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 32b/64b 구조 차이 이해 | 부호(1b)+지수(8/11b)+가수(23/52b) 배치 | bias 값(127/1023)을 빠뜨리지 않을 것 |
| 특수값 구분 능력 | NaN, ±Inf, 비정규화수 판별 조건 | 지수 전체 1과 전체 0의 의미를 혼동하지 않을 것 |
| 반올림 오차 인식 | 유한 가수 비트로 인한 근사 한계 | 0.1 + 0.2 != 0.3 사례를 수식이 아닌 원리로 설명할 것 |

> 요약: 실수를 부호·지수·가수로 분할하여 유한 비트로 넓은 범위를 근사 표현하는 표준임

## Ⅱ. 구성요소
```text
MSB                                              LSB
+------+-------------+---------------------------+
| Sign |  Exponent   |     Mantissa (Fraction)   |
| 1 bit|  8b or 11b  |     23b or 52b            |
+------+-------------+---------------------------+
   |         |                    |
   v         v                    v
 양/음    2^(E-bias)         1.xxxxx (정규화 시 숨은 1)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 부호 비트(Sign) | 0이면 양수, 1이면 음수를 나타내는 1비트 플래그임 | 수표 앞 +/- 기호 |
| 지수(Exponent) | bias를 뺀 뒤 2의 거듭제곱 크기를 결정함 (단정밀도 bias=127) | 과학적 표기의 10^n 부분 |
| 가수(Mantissa) | 유효 숫자를 저장하며 정규화 시 숨은 1(implicit 1)이 앞에 붙음 | 과학적 표기의 유효숫자 부분 |
| 숨은 비트(Hidden bit) | 정규화된 수는 항상 1.xxx 형태이므로 1을 저장하지 않아 1비트 절약함 | 항상 붙는 접두사를 생략하는 약속 |
| 특수값 영역 | 지수 전체 0(비정규화/±0)과 전체 1(±Inf/NaN)을 구별하는 예약 패턴임 | 우편번호 중 특수 용도 예약 번호 |

> 요약: 부호·지수·가수 세 필드와 숨은 비트·특수값 예약 패턴으로 구성됨

## Ⅲ. 절차
```text
실수값 입력 --> 부호 결정 --> 이진 변환 --> 정규화
     |                                        |
     v                                        v
  결과 저장 <-- bias 더해 지수 인코딩 <-- 가수 절삭/반올림
```
- 1단계: 부호 결정 — 양수이면 0, 음수이면 1을 부호 비트에 기록함
- 2단계: 절대값을 이진 소수로 변환 — 정수부는 2로 나누기, 소수부는 2를 곱하기를 반복함
- 3단계: 정규화 — 1.xxxx × 2^e 형태로 소수점을 이동하고, 숨은 1을 제거한 나머지를 가수 필드에 채움
- 4단계: 지수 인코딩 및 반올림 — 지수에 bias를 더해 지수 필드에 저장하고, 가수 비트를 초과하는 부분은 반올림 모드(nearest-even 등)에 따라 절삭함

> 요약: 부호 결정 → 이진 변환 → 정규화 → 지수 bias 인코딩·가수 반올림 순서로 실수를 비트 패턴에 매핑함

## Ⅳ. 문제점
- 반올림 오차 누적: 유한 가수 비트로 표현 불가능한 값이 근사되며, 반복 연산 시 오차가 누적되어 결과 신뢰도가 저하됨
- 비교 연산 불안정: 동일 수학적 값이 서로 다른 비트 패턴으로 저장될 수 있어 `==` 비교가 의도와 다르게 동작함
- 표현 범위 비대칭: 0 근처(비정규화 영역)에서 유효 자릿수가 줄어들어 정밀도가 급격히 감소함

> 요약: 유한 비트 근사로 인한 반올림 누적, 비교 불안정, 0 근처 정밀도 저하가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 오차 허용 범위(epsilon) 기반 비교 함수를 도입하여 비교 연산 불안정을 완화함
2. 중기: Kahan Summation 등 보상 알고리즘을 적용하여 반복 연산 시 반올림 오차 누적을 억제함
3. 장기: 임의 정밀도 산술(arbitrary-precision) 라이브러리 또는 128비트 확장 정밀도를 도입하여 0 근처 정밀도 저하를 해소함

> 요약: epsilon 비교, 보상 알고리즘, 확장 정밀도 도입으로 각 문제에 대응함

## Ⅵ. 전망
- 발전 방향: AI 학습에서 bfloat16·FP8 등 저정밀 포맷이 확산되고, 용도별 정밀도 선택이 세분화되는 추세임
- 기술사적 판단: 수치 연산 신뢰성과 성능 간 트레이드오프를 이해하는 것이 시스템 설계의 기본 역량임
- 기술사 제언: 도메인별 정밀도 요구를 분석하고, 혼합 정밀도(mixed-precision) 전략을 수립하여 연산 효율과 정확도를 균형 있게 확보할 것을 권고함
