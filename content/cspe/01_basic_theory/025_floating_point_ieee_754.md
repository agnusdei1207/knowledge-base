## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IEEE 754는 실수를 **부호(Sign) · 지수(Exponent) · 가수(Mantissa/Significand)**의 3필드로 이진 표현하는 국제 표준이다. 단정밀도(float, 32비트)와 배정밀도(double, 64비트)가 대표적이며, 유효 숫자의 정밀도와 표현 범위를 결정한다.
> 2. **가치**: 과학 계산, 3D 그래픽, 금융, AI/ML 등 실수 연산이 필요한 모든 분야의 **공통 언어**이다. 부동소수점의 한계(반올림 오차, NaN, Infinity)를 이해하지 않으면 "0.1 + 0.2 ≠ 0.3" 같은 버그에 무방비하게 노출된다.
> 3. **융합**: GPU(FP16/BF16 행렬 연산), 데이터베이스(DECIMAL vs FLOAT), 네트워크(지연 시간 계산), 보안(타이밍 공격 방지), AI(혼합 정밀도 학습) 등 정밀도-성능 트레이드오프가 핵심인 모든 분야에 적용된다.

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| **IEEE 754** | 부동소수점 수의 이진 표현 국제 표준. 부호·지수·가수 3필드로 구성 | "실수의 여권 양식" |
| **편향 지수(Biased Exponent)** | 음의 지수를 양수로 저장하기 위해 고정값(bias)을 더한 지수. 단정밀도 bias=$127$ | "해발 고도 기준점" |
| **가수(Mantissa/Significand)** | 유효 숫자를 저장하는 필드. 정규화 시 암묵적 1(hidden bit)이 생략됨 | "과학적 표기법의 유효 숫자" |
| **NaN(Not a Number)** | 정의되지 않는 연산($0/0$, $\sqrt{-1}$)의 결과. $\text{NaN} \neq \text{NaN}$이 유일한 성질 | "계산기의 ERROR" |
| **머신 엡실론($\epsilon$)** | $1 + \epsilon \neq 1$을 만족하는 가장 작은 양수. 부동소수점의 최소 분해능 | "저울의 최소 눈금" |

## Ⅰ. 개요 및 필요성

- **개념**: IEEE 754 단정밀도(32비트)는 1비트 부호 + 8비트 지수 + 23비트 가수로 구성된다. 실수 V = (-1)^S × 1.M × 2^(E-127)이다. 지수에 편향(bias=127)을 더하여 음의 지수도 양수로 저장한다. "1.M"에서 정수부 1은 암묵적(hidden bit)으로 저장하지 않아 유효 숫자가 24비트가 된다.

- **필요성**: 정수만으로는 과학 계산(아보가드로 수 6.022×10²³, 전자 질량 9.109×10⁻³¹)을 표현할 수 없다. 부동소수점은 유한 비트로 매우 크거나 작은 실수를 근사적으로 표현하되, 유효 숫자의 정밀도를 보장한다.

- **비유**: IEEE 754는 **과학적 표기법(Scientific Notation)**의 이진 버전이다. 3.14 × 10²는 부호(+), 가수(3.14), 지수(2)로 분리된다. IEEE 754도 동일한 구조를 이진법으로 구현한 것이다.

- **등장 배경 및 발전 과정**:
  1. **1985년**: IEEE 754-1985 표준 제정. William Kahan(UC Berkeley)이 주도하여 1989년 튜링상을 수상했다.
  2. **2008년**: IEEE 754-2008으로 개정. 반정밀도(16비트), 사정밀도(128비트), 10진 부동소수점(decimal64/128) 추가.
  3. **현대**: AI에서 BFloat16(Brain Floating Point), FP8 등 저정밀도 포맷이 등장하여 학습 속도와 메모리 효율을 극대화하고 있다.

```text
+-----------------------------------------------------------------------+
|        IEEE 754 단정밀도 (32비트) 구조                                |
+-----------------------------------------------------------------------+
|                                                                       |
|  비트:  31  30----23  22-----------0                                 |
|        [S] [EEEEEEEE] [MMMMMMMMMMMMMMMMMMMMMMM]                      |
|        부호  지수(8비트)  가수(23비트)                                |
|                                                                       |
|  예시: -6.5₁₀ = -1.101₂ × 2² 를 IEEE 754로 변환                    |
|                                                                       |
|  Step 1: 부호 S = 1 (음수)                                           |
|  Step 2: 정규화 -6.5 = -1.101 × 2²                                  |
|  Step 3: 지수 E = 2 + 127(bias) = 129 = 10000001₂                   |
|  Step 4: 가수 M = 101 (1.101에서 "1." 생략, 나머지 0 패딩)          |
|                                                                       |
|  결과: 1 10000001 10100000000000000000000                            |
|        S  E(129)    M(.101)                                          |
|  16진: 0xC0D00000                                                    |
|                                                                       |
|  [정밀도 비교]                                                        |
|  단정밀도 (float):  32비트, 유효 7자리, 범위 ±3.4×10³⁸              |
|  배정밀도 (double): 64비트, 유효 15자리, 범위 ±1.8×10³⁰⁸            |
|  반정밀도 (half):   16비트, 유효 3자리, 범위 ±65504                  |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** -6.5를 IEEE 754 단정밀도로 변환하는 과정을 보여준다. 핵심은 (1) 이진 변환(-6.5 = -110.1₂), (2) 정규화(1.101 × 2²), (3) 편향 지수(2+127=129), (4) 암묵적 1 생략(가수부에 .101만 저장)이다. 단정밀도의 유효 숫자는 약 7자리(10진)이므로, 큰 수에 작은 수를 더하면 작은 수가 사라질 수 있다(소거 오차). 이것이 금융에서 float 대신 Decimal을 쓰는 이유이다.

- **📢 섹션 요약 비유**: IEEE 754는 "실수를 부호·크기·위치로 분해하여 저장하는 표준 양식"입니다. 과학적 표기법(3.14×10²)을 컴퓨터가 이해하는 이진 양식으로 번역한 것입니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 단정밀도(32bit) | 배정밀도(64bit) | 역할 | 비유 |
|:---|:---|:---|:---|:---|
| **부호(S)** | 1비트 | 1비트 | 양수/음수 구분 | ±기호 |
| **지수(E)** | 8비트 (bias=127) | 11비트 (bias=1023) | 소수점 위치 결정 | 자릿수 지정 |
| **가수(M)** | 23비트 (유효 24) | 52비트 (유효 53) | 유효 숫자 저장 | 유효 자릿수 |
| **표현 범위** | ±1.18×10⁻³⁸ ~ ±3.4×10³⁸ | ±2.2×10⁻³⁰⁸ ~ ±1.8×10³⁰⁸ | — | — |

### 특수값 — Infinity, NaN, 비정규화수

```text
+-----------------------------------------------------------------------+
|        IEEE 754 특수값 — 모든 비트 패턴에 의미가 있다                 |
+-----------------------------------------------------------------------+
|                                                                       |
|  지수(E)    가수(M)     의미                   예시                   |
|  ────────────────────────────────────────────────────────            |
|  0          0          ±0 (양의 0, 음의 0)     +0.0, -0.0            |
|  0          ≠0         비정규화수(Denormalized) 매우 작은 수 (점진적  |
|                        → 0에 가까운 수 표현      언더플로우 방지)     |
|  1~254      아무 값    정규화수(Normalized)     일반적인 실수         |
|  255(0xFF)  0          ±∞ (Infinity)           1.0/0.0 = +∞          |
|  255(0xFF)  ≠0         NaN (Not a Number)      0.0/0.0, √(-1)       |
|                                                                       |
|  ★ NaN ≠ NaN: NaN은 자기 자신과도 같지 않다!                        |
|     → if (x != x) → x is NaN (NaN 판별법)                           |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** IEEE 754는 모든 비트 패턴에 의미를 부여한다. 지수가 모두 0이면서 가수도 0이면 ±0, 가수가 0이 아니면 비정규화수(0에 가까운 매우 작은 수를 표현하여 점진적 언더플로우 제공)이다. 지수가 모두 1(0xFF)이면서 가수가 0이면 ±∞(오버플로우 결과), 가수가 0이 아니면 NaN(정의되지 않은 연산 결과)이다. NaN의 가장 유명한 성질은 `NaN ≠ NaN`이며, 이를 이용해 NaN 판별이 가능하다.

- **📢 섹션 요약 비유**: IEEE 754의 특수값은 "계산기에 ERROR가 뜨는 상황"을 체계적으로 분류한 것입니다. 0으로 나누면 ∞, 불가능한 계산이면 NaN(에러), 너무 작은 수면 비정규화수(점진적 소멸).

## Ⅲ. 비교 및 연결

### 비교 1: float vs double vs Decimal

| 비교 항목 | float (32비트) | double (64비트) | Decimal (128비트) |
|:---|:---|:---|:---|
| **유효 자릿수** | ~7자리 | ~15자리 | 28~34자리 |
| **범위** | ±3.4×10³⁸ | ±1.8×10³⁰⁸ | ±7.9×10²⁸ |
| **0.1 표현** | 근사 (오차 발생) | 근사 (오차 발생) | 정확 |
| **연산 속도** | 가장 빠름 | 빠름 | 느림 (소프트웨어) |
| **용도** | 그래픽, 게임, AI | 과학 계산, 범용 | 금융, 회계 |

### 과목 융합 관점
- **AI/ML**: 혼합 정밀도 학습(Mixed Precision Training)은 순전파에 FP16, 역전파에 FP32를 사용하여 학습 속도 2배, 메모리 50% 절감. NVIDIA Tensor Core가 FP16/BF16을 하드웨어 가속한다.
- **금융**: 0.1+0.2≠0.3 오류가 실제 금액 계산에서 발생하면 법적 문제가 된다. 반드시 Decimal/BigDecimal 타입을 사용한다.
- **보안**: 부동소수점 비교(`==`)의 비결정성을 이용한 타이밍 공격이 가능하다. 보안 관련 비교에서는 정수 연산 사용을 권장한다.

- **📢 섹션 요약 비유**: float는 "자 없이 눈대중으로 재기"(빠르지만 부정확), Decimal은 "버니어 캘리퍼스로 재기"(느리지만 정확)입니다. 용도에 맞는 도구를 골라야 합니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — AI 혼합 정밀도 학습**: ResNet-50 학습에 FP32 대신 FP16을 사용하면 메모리 사용량이 절반으로 줄어 배치 크기를 2배로 늘릴 수 있고, Tensor Core 활용으로 학습 속도가 2~3배 향상된다. 단, Loss Scaling으로 기울기 언더플로우를 방지해야 한다.

2. **시나리오 — 금융 시스템 결제 처리**: 은행 송금 시스템에서 float로 금액을 저장하면 1억 원 거래에서 1원 미만의 오차가 누적되어 장부 불일치가 발생한다. BigDecimal(Java) 또는 NUMERIC(PostgreSQL)을 사용해야 한다.

### 안티패턴
- **float로 금액 계산**: 0.1 + 0.2 = 0.30000000000000004. 금융에서 이 오차는 법적 문제이다.
- **부동소수점 동등 비교(`==`)**: 반올림 오차로 인해 `a == b`가 실패한다. `|a - b| < epsilon`(허용 오차 비교)을 사용한다.

- **📢 섹션 요약 비유**: float로 돈 계산은 "자 없이 건물 설계"와 같습니다. 1mm 오차가 100층에서는 10cm가 됩니다.

### 👶 어린이를 위한 3줄 비유 설명

1. 컴퓨터는 소수점이 있는 숫자(3.14)를 부호(+), 숫자(314), 소수점 위치(2번째) 세 가지로 나눠 저장해요.
