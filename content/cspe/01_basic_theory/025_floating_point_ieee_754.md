# 부동소수점 표현 - IEEE 754 (Floating Point IEEE 754)

## 1. 개요

- **정의/개념**: IEEE 754 부동소수점은 실수를 부호, 지수, 가수로 나누어 제한된 비트 안에 근사 표현하는 표준 형식이다.
- **배경/필요성**: 컴퓨터는 무한한 실수를 그대로 저장할 수 없으므로 범위와 정밀도를 균형 있게 제공하는 표준화된 근사 표현이 필요하다.

부동소수점은 정확한 실수 저장 방식이 아니라 넓은 범위를 표현하기 위한 근사 체계라는 점이 핵심이다.

## 2. 특징 및 비교

| 구분 | 정수 표현 | 고정소수점 | 부동소수점 |
|---|---|---|---|
| 표현 대상 | 정수 | 고정된 소수 자리 | 매우 크거나 작은 실수 |
| 정밀도 | 범위 내 정확 | 소수 자리 고정 | 크기에 따라 상대 정밀도 변화 |
| 주요 비용 | overflow | scale 관리 | rounding error |
| 대표 활용 | 카운터, 주소 | 금융 일부 | 과학계산, AI, 그래픽스 |

부동소수점 선택 기준은 표현 범위, 정밀도, 연산 속도, 재현성, 반올림 오차 허용 여부이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Sign | 양수·음수 표시 | 1비트 |
| Exponent | 값의 크기 범위 표현 | bias 적용 |
| Fraction | 유효숫자 저장 | 정밀도 결정 |
| Bias | 지수 음수 표현 보정 | 단정도 127 |
| Special Values | 0, subnormal, infinity, NaN | 예외 처리 |

```text
+------+----------+----------------+
| Sign | Exponent | Fraction       |
+------+----------+----------------+
   |        |             |
   v        v             v
 부호   크기 범위      유효숫자 정밀도
```

이 구조 때문에 부동소수점은 넓은 범위를 표현하지만, 10진 소수를 항상 정확히 저장하지 못해 오차 관리가 필요하다.

## 4. 문제점 및 개선방안

1. **반올림 오차**
   - `0.1` 같은 10진 소수가 2진 부동소수점에서 정확히 표현되지 않을 수 있다.
   - **개선방안**: epsilon 비교, decimal 타입, 정수 스케일링을 적용한다.

2. **비교·누적 오차**
   - 반복 합산과 직접 동등 비교에서 결과가 기대와 달라질 수 있다.
   - **개선방안**: 허용 오차 비교, Kahan summation, 연산 순서 고정을 사용한다.

3. **특수값 처리 누락**
   - NaN, infinity, underflow, overflow를 처리하지 않으면 모델·계산 결과가 오염된다.
   - **개선방안**: 입력 검증, 예외값 모니터링, 수치 안정성 테스트를 수행한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| AI 학습 | FP32, FP16, BF16을 성능과 정밀도 기준으로 선택 | 학습 안정성, 처리량 |
| 금융 계산 | 금액은 정수 또는 decimal로 처리하고 float 사용 제한 | 반올림 오류율 |
| 과학 계산 | 오차 전파와 수치 안정성 고려 | 상대 오차, overflow 발생 |

## 6. 결론

IEEE 754는 실수를 제한된 비트로 표현하기 위한 표준 근사 체계이다. 부호·지수·가수 구조를 이해해야 표현 범위, 정밀도, 특수값, 반올림 오차가 하나의 논리로 연결되며 실무 위험도 설명할 수 있다.
