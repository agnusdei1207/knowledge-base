# 📖 【암기용】 개념 완전 이해

> 목적: 지도·비지도·강화 학습의 차이를 처음 보는 사람도 데이터, 목표, 평가 기준으로 구분하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 학습 문제를 라벨, 구조 발견, 보상 최적화 기준으로 나누는 분류
- **왜 필요한가**: 같은 AI라도 라벨이 있는지, 숨은 패턴을 찾는지, 행동을 선택하는지에 따라 모델·데이터·평가 방법이 달라짐.
- **핵심 직관**: 정답지를 보고 배우면 지도, 정답 없이 묶으면 비지도, 행동 후 보상으로 배우면 강화 학습임.

## 깊이 이해
- **배경·문제의식**: AI 프로젝트 실패는 문제 유형과 학습 방법 불일치에서 자주 발생함. 라벨 없는 고객 데이터를 분류 모델로 시작하거나, 순차 의사결정 문제를 단일 예측으로 축소하면 평가 기준이 흔들림.
- **작동 원리**: 지도 학습은 입력 X와 정답 y의 함수를 학습함. 비지도 학습은 X만으로 군집·차원·분포를 찾음. 강화 학습은 상태에서 행동을 선택하고 보상 누적값을 최대화함.
- **비유**: 지도 학습은 정답 있는 문제집, 비지도 학습은 책 더미를 주제별로 정리, 강화 학습은 게임을 반복하며 점수를 높이는 훈련임.
- **구체 예시**: 스팸 메일 분류는 지도 학습, 고객 세그먼트는 K-Means 비지도 학습, 로봇 경로 제어는 강화 학습으로 모델링함.
- **흔한 오해·주의점**: 강화 학습은 "강한 학습"이 아니라 Reinforcement Learning의 번역임. 보상 설계가 부정확하면 목표와 다른 행동을 학습함.

## 연결 개념
- 분류·회귀 — 지도 학습의 대표 문제
- 군집화·차원축소 — 비지도 학습의 대표 문제
- MDP(Markov Decision Process) — 강화 학습의 수학적 모델

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 학습 패러다임은 데이터 라벨, 목표 함수, 평가 지표에 따라 지도·비지도·강화 학습으로 구분됨.
> 2. **가치**: 문제 유형을 먼저 분류해야 모델 선정, 데이터 구축, 검증 지표가 일관됨.
> 3. **판단 포인트**: 라벨 존재, 목표가 예측인지 구조 발견인지 순차 의사결정인지가 선택 기준임.

---

## Ⅰ. 개요 및 필요성

학습 패러다임은 AI 문제의 분류 기준이다. 데이터와 목표가 맞지 않으면 모델 정확도보다 평가 체계가 먼저 실패함. 기술사 답안에서는 라벨, 목표, 지표, 적용 사례를 표로 구분해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Problem -> Data Condition -> Learning Paradigm -> Model Family -> Metric
          Label 있음       -> Supervised -> Classifier/Regressor -> F1/RMSE
          Label 없음       -> Unsupervised -> Clustering/PCA -> Silhouette
          State/Reward     -> Reinforcement -> Policy/Value -> Return
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 지도 학습 | 입력-정답 쌍으로 예측 함수 학습 | 분류, 회귀, F1, RMSE |
| 비지도 학습 | 라벨 없이 구조·군집·차원 발견 | K-Means, PCA, Silhouette |
| 강화 학습 | 상태-행동-보상으로 정책 학습 | MDP, Q-Learning, Policy Gradient |
| 평가 체계 | 문제 유형별 성공 기준 결정 | Accuracy, AUC, Return |

> 요약: 학습 패러다임은 데이터 조건과 목표 함수에 따라 모델군과 평가 지표를 결정함.

---

## Ⅲ. 동작원리 및 흐름도

```text
업무 목표 확인 -> 라벨 존재 여부 확인 -> 순차 의사결정 여부 확인
-> 지도/비지도/강화 선택 -> 모델 학습 -> 지표 검증 -> 배포 판단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문제 목표를 예측·구조 발견·행동 선택으로 분류 | 요구사항 문장 |
| 2 | 데이터 라벨과 보상 신호 확인 | y 존재, Reward 설계 |
| 3 | 적합한 모델군과 손실 함수 선택 | Cross-Entropy, MSE, Return |
| 4 | 평가 지표로 검증 후 운영 반영 | F1, Silhouette, 누적 보상 |

> 요약: 업무 목표와 데이터 조건을 먼저 판정한 뒤 학습 방식과 지표를 연결해야 함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 지도 학습 | 정답 라벨 기반 예측 | 라벨 정확도 95% 이상, F1 |
| 비지도 학습 | 숨은 구조 탐색 | 군집 수 k, Silhouette 0.5 이상 |
| 강화 학습 | 행동 정책과 누적 보상 학습 | 보상 설계, Episode Return |

> 요약: 세 학습 방식은 라벨·구조·보상이라는 입력 조건이 다르므로 같은 지표로 비교하지 않음.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 모델명 중심 접근 | 문제-데이터-지표 매핑 | 요구사항 분석 단계 |
| 비용/성능 | 라벨 전량 구축 | 비지도·반지도 병행 가능 | 라벨 비용 건당 단가 |
| 운영/위험 | 지표 불일치로 배포 실패 | 패러다임별 지표 분리 | KPI와 모델 지표 정합 |

> 요약: 학습 방식은 모델 유행보다 데이터 조건과 평가 지표의 정합성으로 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문제 유형 오분류 | 라벨·보상 조건 미확인 | 요구사항-데이터 매핑표 작성 | 재작업 건수 |
| 지표 불일치 | 업무 KPI와 ML 지표 분리 | KPI-F1/RMSE/Return 연결 | 운영 KPI 편차 |
| 보상 해킹 | 강화 학습 보상 설계 결함 | 제약 조건, 시뮬레이터 검증 | 위반 행동 비율 |

> 요약: 학습 패러다임 리스크는 요구사항, 지표, 보상 설계를 문서화해 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 적합성 | 라벨 품질 95% 이상 또는 보상 명세 완료 | 샘플 검수, 데이터 프로파일링 |
| 모델 검증 | F1 0.85, Silhouette 0.5, Return 기준선 초과 | 검증셋, 군집 평가, 시뮬레이션 |
| 운영/보안 | 데이터 드리프트 월 1회 점검 | 모니터링, PSI, 감사 로그 |

> 요약: 도입 후에는 패러다임별 지표와 데이터 드리프트를 분리 측정해야 함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 요구사항 분류: 예측, 군집, 제어 중 하나로 문제를 분류하고 라벨·보상 존재 여부를 확인.
2. 지표 설계: 지도는 F1/AUC/RMSE, 비지도는 Silhouette/DBI, 강화 학습은 누적 보상과 제약 위반율로 평가.
3. 운영 검증: 월 1회 데이터 드리프트 PSI 0.2 이상 탐지 시 재학습 후보 등록.

**결론 (2줄):**
- 기술사 판단: 라벨이 있으면 지도, 라벨 없이 패턴을 찾으면 비지도, 행동과 보상이 있으면 강화 학습으로 시작함.
- 향후 방향: 실무 AI는 반지도·자기지도·온라인 학습을 결합해 라벨 비용과 운영 드리프트를 함께 다룸.
