## Ⅰ. 개요
- **정의**: 유한 기호 집합과 생성 규칙으로 구성된 문자열 집합을 수학적으로 정의·분류하는 이론임
- **배경/필요성**: 프로그래밍 언어 구문의 엄밀한 정의 → 컴파일러·파서 설계의 수학적 기반 제공 필수
- **비유**: 레고 블록(알파벳)과 조립 설명서(문법)로 허용된 완성품(언어)만 만드는 체계

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 촘스키 계층 4단계 구분 | Type 0~3 문법과 대응 오토마타 | 각 계층의 표현력·인식기 1:1 매핑 필수 |
| 문법의 생성력과 한계 | 정규 vs 문맥자유 vs 문맥의존 차이 | 자연어=Type 0이 아님을 명시 |

> 요약: 기호와 규칙 기반으로 언어를 수학적으로 정의하고 촘스키 계층으로 표현력을 분류하는 이론임

## Ⅱ. 구성요소
```text
+----------+     +----------+     +----------+     +----------+
| Alphabet | --> | Grammar  | --> | Language | --> | Automata |
| (Sigma)  |     | (G=V,T,  |     | L(G)     |     | (DFA/PDA |
|          |     |  P,S)    |     |          |     |  /TM)    |
+----------+     +----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 알파벳(Σ) | 언어를 구성하는 기호의 유한 집합, 예: {0, 1} 또는 {a, b, c} | 블록 조각 |
| 문법(G) | 4-튜플 (V, T, P, S)로 정의, 생성 규칙 P로 유효 문자열 도출 | 조립 설명서 |
| 오토마타 | 문법이 생성한 언어를 인식하는 기계 — DFA, PDA, LBA, TM으로 계층 대응 | 검수 로봇 |

> 요약: 알파벳 → 문법(생성 규칙) → 언어(문자열 집합) → 오토마타(인식기) 순의 4단 체계임

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| Define   | -> | Set Prod | -> | Derive   | -> | Recognize|
| Symbols  |    | Rules    |    | Strings  |    | by Auto  |
+----------+    +----------+    +----------+    +----------+
```

1. **기호 정의** — 터미널(T)과 비터미널(V) 기호 집합, 시작 기호(S)를 명세함
2. **생성 규칙 설정** — 비터미널을 터미널·비터미널 조합으로 치환하는 규칙 P를 정의함
3. **문자열 유도** — 시작 기호 S에서 P를 반복 적용하여 유효 문자열(w ∈ L(G))을 도출함
4. **오토마타 인식** — 유도된 문자열이 해당 계층 오토마타(DFA/PDA/TM)에서 수용 여부 판별함

> 요약: 기호·규칙 정의 → 문자열 유도 → 오토마타 인식의 생성-검증 사이클로 언어를 형식화함

## Ⅳ. 문제점
- [표현력 한계]: 정규 문법(Type 3)은 괄호 매칭 불가, 문맥자유(Type 2)는 교차 의존성 표현 불가
- [파싱 복잡도]: 표현력이 높은 문법일수록 인식 알고리즘 시간 복잡도 증가 (CYK: O(n³))
- [모호성 문제]: 동일 문자열에 대해 2개 이상 파스 트리가 존재하는 모호 문법 발생 시 해석 불확정

> 요약: 계층별 표현력 제약, 고표현력 문법의 파싱 비용, 모호 문법의 비결정성이 핵심 과제임

## Ⅴ. 개선방안
1. 단기: LL/LR 파싱 가능 형태로 문법 규칙을 재작성(좌측 인수분해 등)하여 모호성 제거
2. 중기: LALR 파서 생성기(Yacc/Bison)를 활용하여 O(n) 선형 시간 파싱 달성 (상세 → 074 참조)
3. 장기: 뉴로심볼릭 접근으로 형식 문법과 LLM을 결합, 자연어 수준 의미 분석까지 확장

- [과도한 제약]: 문법 제한이 언어 확장성 저해 → 문법 계층 전환 기준을 정량화 (지표: 규칙 수 대비 표현 커버리지)

> 요약: 문법 재작성 → 파서 생성기 활용 → 뉴로심볼릭 융합 순으로 형식 언어의 실용성을 확대함

## Ⅵ. 전망
- 향후 발전 방향: DSL(Domain-Specific Language) 설계 시 형식 문법의 자동 검증·생성 도구 확산
- 기술사적 판단: LLM 시대에도 프로그래밍 언어 파서·정규표현식 엔진의 이론적 기초로서 불가결
- 기술사 제언: 컴파일러·프로토콜 설계 시 요구되는 표현력 수준을 촘스키 계층에 매핑하여 적정 문법 계층을 선택할 것
