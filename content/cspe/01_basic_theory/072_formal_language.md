## 미리 알고가기

- 알파벳(Alphabet): 문자열을 구성하는 기호 집합임
- 문법(Grammar): 문자열을 생성하는 기호와 생성 규칙의 집합임
- 오토마타(Automata): 입력 문자열을 상태 전이로 읽고 수용 여부를 판단하는 추상 기계임
- 촘스키 계층: 문법 제약과 인식 기계의 능력에 따라 언어를 나누는 분류임
- 단말·비단말 기호: 최종 문자열에 남는 입력 기호와 생성 과정에서 치환되는 기호임
- 비축약 규칙: 생성 규칙의 우변 길이가 좌변보다 짧아지지 않는 규칙임
- 유한·푸시다운 오토마타: 각각 유한 상태와 스택으로 문자열을 인식하는 기계임
- 선형 제한 오토마타·튜링 머신: 각각 입력 길이에 비례해 제한된 테이프와 무제한 테이프를 사용하는 기계임
- 재귀 열거 언어: 튜링 머신이 언어에 속하는 문자열은 수용하지만 속하지 않는 문자열에서는 종료하지 않을 수 있는 언어임
- 문법 기호: $V_n$은 비단말 집합, $V_t$는 단말 집합, $P$는 생성 규칙, $S$는 시작 기호, $\epsilon$은 빈 문자열임

## 작성 근거(검토용)

- **방향성**: 형식 언어 이론은 문법 제약이 완화될수록 표현 범위와 인식 기계의 기억장치 요구가 커지므로, 필요한 구조 복잡도보다 강한 문법 계층을 쓰지 않고 토큰은 정규 언어, 중첩 구문은 문맥 자유 문법처럼 최소 계층을 선택해야 함
- **Ⅰ. 개요 구성**: 생성 문법과 인식 오토마타를 함께 제시해 이론의 두 축을 모두 드러냄
- **Ⅱ. 특징 선정**: 문법 제약과 인식 기계 능력의 대응 관계를 촘스키 계층의 구조적 성질로 제시함
- **Ⅲ. 비교축 선정**: 정규·문맥 자유·문맥 의존·무제약 언어는 상호 배타적 선택 대상이 아니라 포함 관계의 계층이므로 적용 기준 축을 강제하지 않고, 생성 규칙·인식 모델·표현 범위로 계층별 대응을 보여줌
- **Ⅳ. 구조 선정**: 문법의 4원소와 예시 규칙을 제시해 추상 정의 이해를 도움
- **Ⅵ. 사례 선정**: 컴파일러의 토큰·중첩 구문 분리와 연산자 우선순위 명시는 형식 언어가 실제 파서 설계로 이어지는 핵심 지점임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 촘스키 계층 등 미리 알고가기 용어가 본문에서 실제로 쓰이는지 확인했으며 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 형식 언어 이론은 문자열 집합을 문법으로 생성하고 오토마타로 인식하는 계산 이론임
- **배경/필요성**: 프로그래밍 언어와 프로토콜의 구문을 명확히 정의하기 위해 문법과 인식 한계를 다루는 수학적 체계가 필요함

### 쉽게 이해하기 (학습용)
- 요리법(문법)대로 요리를 만들고, 그 요리가 요리법대로 만들어졌는지 검사기(오토마타)로 확인하는 것과 같음

## Ⅱ. 특징

- 문법 제약이 완화될수록 생성 가능한 언어 범위와 인식 기계의 기억장치가 확대됨
- 정규 언어는 상태만으로, 문맥 자유 언어는 스택으로 구조를 인식함
- 문법과 오토마타를 대응시켜 생성 가능성과 인식 가능성을 함께 판단함
- 컴파일러 어휘·구문 분석의 이론적 기준을 제공함

### 쉽게 이해하기 (학습용)
- 요리법의 제약이 느슨해질수록 더 다양한 요리를 만들 수 있지만 검사기도 더 똑똑해야 함
- 단순한 요리는 메모 한 장(상태)만 봐도 검사되지만, 중첩된 요리는 임시 그릇 더미(스택)가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 언어 | 문맥 자유 언어 | 문맥 의존 언어 | 무제약 언어 |
|:---|:---|:---|:---|:---|
| 생성 규칙 | $A \to aB \mid a$ 형식 | 단일 비단말 좌변 | 비축약 규칙 | 무제약 규칙 |
| 인식 모델 | 유한 오토마타 | 푸시다운 오토마타 | 선형 제한 오토마타 | 튜링 머신 |
| 표현 범위 | 토큰 패턴 | 중첩 구문 | 문맥 제약 | 재귀 열거 언어 |

> 요약: 촘스키 계층은 생성 규칙 제약이 완화될수록 정규·문맥 자유·문맥 의존·무제약 언어 순으로 표현 범위와 인식 능력이 확대되는 분류 체계임.

### 쉽게 이해하기 (학습용)
- 요리법이 "재료 하나만 바꿔라"처럼 단순할수록 감시원 한 명(유한 오토마타)으로 충분하지만, 규칙이 복잡해질수록 기록 도구(스택, 테이프)가 점점 더 필요해짐

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 단말 기호 | 최종 문자열에 남는 입력 기호 |
| 비단말 기호 | 생성 과정에서 치환되는 중간 기호 |
| 생성 규칙 | 좌변을 우변 문자열로 바꾸는 규칙 |
| 시작 기호 | 문자열 생성을 시작하는 비단말 기호 |

```text
[ 형식 문법 구조 ]
G = (V_n, V_t, P, S)
S -> aSb | ε
```

> 요약: 형식 문법은 단말·비단말 기호와 생성 규칙으로 문자열 집합을 정의함.

### 쉽게 이해하기 (학습용)
- 완성된 요리에 남는 재료(단말 기호)와 조리 중에만 쓰이는 중간 표시(비단말 기호)를 레시피 규칙대로 시작 재료부터 바꿔가며 요리를 완성하는 것과 같음

## Ⅵ. 실무 사례

1. 컴파일러는 토큰 패턴을 정규식으로, 중첩 구문을 문맥 자유 문법으로 정의함
2. 프로그래밍 언어 문법은 연산자 우선순위·결합 규칙을 명시해 하나의 구문 트리로 해석되게 함

### 쉽게 이해하기 (학습용)
- 단어 하나하나는 간단한 규칙(정규식)으로, 문장 전체 구조는 더 정교한 규칙(문맥 자유 문법)으로 나눠 검사함

## Ⅶ. 결론

- 형식 언어 이론은 표현하려는 구조의 복잡도에 맞춰 문법 계층과 인식 기계를 선택하는 기준임
- 필요한 표현력보다 강한 문법은 구현·검증 비용을 키우므로 토큰은 정규 언어, 중첩 구문은 CFG처럼 책임을 분리해야 함

### 쉽게 이해하기 (학습용)
- 필요한 만큼만 복잡한 도구를 골라야지, 간단한 검사에 너무 강력한 도구를 쓰면 오히려 비용만 커짐
