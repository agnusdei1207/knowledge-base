## 미리 알고가기

- 촘스키 계층($Chomsky$ $Hierarchy$): 형식 문법을 그 표현 능력에 따라 네 가지 단계로 구분한 이론적 위계 분류임
- 오토마타($Automata$): 특정 형식 언어를 읽어 들이고 수용($Accept$)할 수 있는지 상태 전이를 통해 판별하는 추상적 계산 기계 모델임
- 정규 문법($Regular$ $Grammar$): 촘스키 계층의 가장 단순한 문법($Type-3$)으로, 유한 오토마타($FA$)를 통해 판별 가능한 언어 규칙임
- 문맥 자유 문법($CFG$): 프로그래밍 언어의 구문을 주로 정의하는 문법($Type-2$)으로, 푸시다운 오토마타($PDA$, 스택 보유)로 인식됨

## Ⅰ. 개요

- **정의/개념**: 형식 언어 이론은 수학적으로 엄밀히 정의된 문자열 집합(언어)을 생성하는 유한한 생성 규칙(문법)과, 이를 인식하여 유효성을 판정하는 가상의 기계(오토마타) 사이의 상호 관계를 다루는 컴퓨터 과학의 핵심 이론임
- **배경/필요성**: 자연어처럼 모호한 언어는 컴퓨터가 번역하거나 파싱할 수 없으므로, 프로그래밍 언어의 문법과 네트워크 규격($Protocol$) 등을 엄밀히 규정하고 자동 컴파일러를 구현하기 위해 도입됨

## Ⅱ. 특징

- 촘스키 계층구조를 통해 언어의 문법 구조가 복잡해질수록(Type-3 $\rightarrow$ Type-0) 이를 판정하기 위해 스택, 테이프 등 기억장치가 추가된 더 높은 단계의 가상 기계(오토마타)가 필요함을 밝힘
- 각 형식 언어는 생성하는 규칙의 제약 정도에 따라 수학적 닫힘 성질($Closure$ $Properties$)과 결정 가능성($Decidability$)이 달라져, 이론적 처리 한계를 명확히 규정함
- 텍스트 검색에 쓰이는 정규 표현식($Regular$ $Expression$)부터 컴퓨터 전체의 계산 능력을 대변하는 튜링 머신($Turing$ $Machine$)까지 아우르는 추상 연산론의 뼈대를 형성함

## Ⅲ. 종류 및 비교 (촘스키 계층)

| 계층 (Type) | 언어 종류 | 문법 생성 규칙 제약 ($A \rightarrow \alpha$) | 인식 오토마타 | 주요 활용 분야 |
|:---|:---|:---|:---|:---|
| **Type 3** | 정규 언어 ($Regular$) | $A \rightarrow aB$ 또는 $A \rightarrow a$ (우선형) | 유한 오토마타 ($FA$) | 컴파일러 어휘 분석 ($Lexer$), 정규식 |
| **Type 2** | 문맥 자유 ($Context-Free$) | $A \rightarrow \alpha$ (좌변은 오직 단일 변수) | 푸시다운 오토마타 ($PDA$) | 컴파일러 구문 분석 ($Parser$), $XML$ |
| **Type 1** | 문맥 의존 ($Context-Sensitive$) | $|\beta| \ge |\alpha|$ (길이가 줄어들지 않음) | 선형 유한 오토마타 ($LBA$) | 인간 언어의 구조 분석, 번역기 |
| **Type 0** | 무제약 언어 ($Unrestricted$) | 제약 없음 | 튜링 머신 ($Turing$ $Machine$) | 컴퓨터가 계산 가능한 모든 문제 정의 |

> 요약: 정규 언어는 메모리 없이 상태만 보고, 문맥 자유는 스택 메모리를 쓰며, 튜링 머신은 양방향 읽기/쓰기가 가능한 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변수 기호 ($V_N$) | 문법 생성 규칙에서 다른 기호로 대체될 수 있는 논리적 중간 상태(비단말 기호)임 |
| 단말 기호 ($V_T$) | 알파벳에 속하며, 더 이상 다른 기호로 변환되지 않는 최종 문자열 구성 단위임 |
| 생성 규칙 ($P$) | 좌변의 기호 문자열을 우변의 기호 문자열로 치환하는 수학적 규칙 집합임 |
| 시작 기호 ($S$) | 문자열 생성을 시작하는 출발점이 되는 특별한 비단말 기호임 |

```text
[ 형식 문법의 수학적 4원조 정의 ]
G = (V_N, V_T, P, S)
- 예시 규칙 (CFG): S -> aSb | ε (a와 b의 개수가 같은 문자열 생성)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 알파벳 정의  | --> | 생성규칙(P)설계| --> | 오토마타 상태| --> | 수용여부 결정|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **어휘 집합 선언** — 언어를 구성할 최종 단말 기호($V_T$)와 문법 작성 과정에서 임시 분기로 쓸 비단말 기호($V_N$)를 선언함
2. **치환 규칙 정의** — 시작 기호 $S$로부터 시작하여 단말 기호들만 남을 때까지 치환해 나갈 수 있는 생성 규칙 $P$를 촘스키 규칙 제약에 맞추어 기술함
3. **오토마타 매핑** — 작성된 문법을 인식할 수 있는 적절한 오토마타 기계를 설계하며, 상태 전이 함수($\delta$)와 메모리 제어 규칙을 규정함
4. **유효성 판정** — 검증 대상 문자열이 들어왔을 때 오토마타의 상태가 입력이 끝난 시점에 최종 수용 상태($Accepting$ $State$)에 도달하는지 추적함

## Ⅵ. 실무 적용 및 유의점

1. 프로그래밍 언어 설계 시 정규 표현식으로 처리할 수 있는 간단한 어휘 패턴(예: 변수명, 숫자 포맷)에 복잡한 문맥 자유 문법($CFG$) 파서를 남용하면 컴파일 속도가 현저히 느려지므로, 어휘 분석기($Lexer$, 정규식)와 구문 분석기($Parser$, CFG)의 역할을 철저히 분리해야 함
2. 문맥 자유 문법을 사용해 파서를 제작할 때, 규칙의 모호성($Ambiguity$)이 존재하여 동일한 문장에 대해 두 개 이상의 파스 트리($Parse$ $Tree$)가 생성될 수 있으므로, 연산자 우선순위 규칙 등을 문법 정의에 삽입해 모호성을 제거해야 함

## Ⅶ. 결론

- 형식 언어 이론은 논리적 기호와 기계 연산력의 한계를 엄밀하게 연결 짓는 컴퓨터 과학의 뿌리이며, 설계자는 해결하고자 하는 패턴의 복잡도에 맞는 최소한의 촘스키 계층 모델을 선택하여 연산 효율성과 분석 신뢰성을 극대화해야 함
