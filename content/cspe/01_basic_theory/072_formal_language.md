## 미리 알고가기

- 언어: 특정 규칙에 따라 생성되는 문자열 집합임
- 문법: 언어를 생성하는 규칙 체계임
- 오토마타: 언어를 인식하는 계산 모델임

## Ⅰ. 개요

- **정의/개념**: 형식 언어 이론은 문자열 집합을 문법과 오토마타로 정의하고, 표현력과 계산 가능성을 계층적으로 분석하는 계산 이론의 핵심 분야임
- **배경/필요성**: 프로그래밍 언어, 프로토콜, 패턴 인식은 모두 허용 가능한 문자열 구조를 엄밀히 정의해야 하므로 형식적 모델이 필요함

## Ⅱ. 특징

- 언어, 문법, 오토마타를 대응시켜 표현력 차이를 설명함
- 촘스키 계층으로 문제 복잡도와 인식 모델을 구분함
- 컴파일러, 검증, 프로토콜 분석의 이론 기반이 됨
- 실제 구현에서는 이론보다 효율적 근사와 제약이 추가됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규 언어 | 문맥 자유 언어 | 문맥 의존/무제약 언어 |
|:---|:---|:---|:---|
| 대표 문법 | Type-3 | Type-2 | Type-1/0 |
| 인식 모델 | FA | PDA | LBA/TM |
| 표현력 | 낮음 | 중간 | 높음 |
| 대표 적용 | Lexer | Parser | 계산 가능성 이론 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 알파벳 | 사용 가능한 기호 집합이며 언어의 재료임 |
| 생성 규칙 | 문자열을 만드는 규칙이며 문법 표현력의 핵심임 |
| 인식기 | 문자열 수용 여부를 판정하고 계산 모델과 연결됨 |
| 계층 구조 | 언어 클래스 포함 관계이며 문제 난도 판단 기준임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 규칙정의 | --> | 언어생성 | --> | 모델인식 | --> | 표현력판단 |
+----------+     +----------+     +----------+     +----------+
```

1. **규칙정의**: 생성할 문자열 패턴을 문법으로 정의함
2. **언어생성**: 문법이 허용하는 문자열 집합을 형성함
3. **모델인식**: 적절한 오토마타로 수용 가능성을 판정함
4. **표현력판단**: 상위/하위 언어 클래스와 비교함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 표현력과 효율 사이 trade-off가 존재해 강한 문법일수록 처리 비용이 커짐
   - 해결방안: 필요한 수준까지만 상위 문법을 사용하고 parser complexity로 검증함
2. 문제: 실무 구현은 이론 모델과 차이가 있어 오류 처리와 복구가 추가되어야 함
   - 해결방안: 형식 모델 위에 pragmatic parsing 전략을 얹음 error recovery rate로 검증함
3. 문제: 계층 구분을 잘못하면 설계가 과해질 수 있어 단순 패턴에 복잡한 파서를 도입할 수 있음
   - 해결방안: 문제 구조에 맞는 최소 언어 클래스를 선택하고 implementation cost로 검증함

## Ⅶ. 적용 사례

- 컴파일러 설계에서는 어휘와 구문 분석 단계를 분리함, 확인 지표는 파싱 정확도임
- 프로토콜 검증에서는 허용 메시지 시퀀스를 모델링함, 확인 지표는 규칙 위반 탐지율임
- 보안 필터링에서는 패턴 허용 범위를 형식화함, 확인 지표는 오탐/미탐 비율임

## Ⅷ. 결론

형식 언어 이론의 핵심은 문제를 표현 가능한 최소 모델로 줄이는 데 있으므로, 구현 전 먼저 언어 클래스와 인식 모델 수준을 판단해야 함.
