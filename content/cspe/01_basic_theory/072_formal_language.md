# 형식 언어 이론 (Formal Language Theory)

## 1. 개요

- **정의/개념**: 형식 언어 이론은 기호 문자열의 집합을 문법과 인식기로 정의하고, 언어의 표현력과 계산 가능성을 분류하는 이론이다.
- **배경/필요성**: 프로그래밍 언어, 정규식, 파서, 계산 모델을 체계적으로 설계하려면 어떤 구조를 어떤 문법과 인식기로 처리할 수 있는지 기준이 필요하다.

형식 언어의 핵심은 문자열을 임의 규칙이 아니라 문법 계층과 인식기 능력으로 설명하는 것이다.

## 2. 특징 및 비교

| 계층 | 문법 | 인식기 | 대표 대상 |
|---|---|---|---|
| Type-3 | 정규 문법 | 유한 오토마타 | 토큰, 정규식 |
| Type-2 | 문맥 자유 문법 | Pushdown Automata | 구문 구조 |
| Type-1 | 문맥 의존 문법 | Linear Bounded Automata | 문맥 의존 규칙 |
| Type-0 | 무제한 문법 | Turing Machine | 계산 가능 언어 |

선택 기준은 표현해야 할 구조의 복잡도, 필요한 메모리 모델, 파싱 가능성, 구현 비용이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Alphabet | 기호 집합 | 문자열 구성 |
| String | 기호의 유한 나열 | 언어 원소 |
| Language | 문자열 집합 | 정의 대상 |
| Grammar | 문자열 생성 규칙 | 표현 방식 |
| Recognizer | 문자열 수용 여부 판단 | 구현 모델 |

```text
문법 계층 -> 생성 가능한 문자열 구조 -> 필요한 인식기 -> 구현 방식
```

문법이 강해질수록 표현력은 커지지만 인식과 구현 비용도 증가한다.

## 4. 문제점 및 개선방안

1. **계층 오용**
   - 정규식으로 문맥 자유 구조를 처리하려 하면 복잡하고 불안정해진다.
   - **개선방안**: 토큰은 정규 언어, 구문은 CFG처럼 역할을 분리한다.

2. **표현력과 효율 혼동**
   - 더 강한 문법이 항상 좋은 구현 선택은 아니다.
   - **개선방안**: 필요한 표현력의 최소 계층을 선택한다.

3. **이론과 구현 단절**
   - 문법 정의가 실제 파서·검증기와 다르면 오류 처리가 어려워진다.
   - **개선방안**: grammar spec, parser generator, 테스트 케이스를 함께 관리한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 컴파일러 | 어휘 분석은 정규 언어, 구문 분석은 CFG로 분리 | 파싱 성공률 |
| 입력 검증 | 단순 패턴은 정규식, 중첩 구조는 parser 사용 | 오탐·미탐 |
| DSL 설계 | 문법 계층에 맞춰 언어 스펙 작성 | 모호성, 구현 비용 |

## 6. 결론

형식 언어 이론은 문자열 구조를 문법과 인식기 관점에서 분류하는 기초 이론이다. 촘스키 계층을 암기표로만 쓰지 말고 표현력, 인식기, 구현 비용의 선택 기준으로 연결해야 한다.
