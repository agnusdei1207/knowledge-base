## 미리 알고가기

- 결정 문제(Decision Problem): 답이 예 또는 아니오로 표현되는 문제임
- 다항 시간(Polynomial Time): 수행 시간이 입력 크기의 다항식으로 제한되는 시간 범위임
- 복잡도 클래스 P: 결정론적 알고리즘으로 다항 시간에 해결할 수 있는 결정 문제 집합임
- 복잡도 클래스 NP: 주어진 해 후보를 다항 시간에 검증할 수 있는 결정 문제 집합임
- NP-완전 문제(NP-Complete): NP에 속하면서 모든 NP 문제가 다항 시간에 환원되는 문제 집합임
- NP-난해 문제(NP-Hard): 모든 NP 문제가 다항 시간에 환원되며 NP 밖의 문제도 포함할 수 있는 집합임
- 다항 시간 환원(Polynomial-Time Reduction): 한 문제를 다른 문제로 다항 시간에 바꿔 난도를 비교하는 방법임
- 논리식 충족 가능성 문제(SAT): 변수 조합의 해 존재 여부를 판정하며 3-SAT는 각 절의 리터럴을 3개로 제한한 대표 버전임
- 그래프 동형 문제(Graph Isomorphism): 두 그래프의 노드 이름이 달라도 연결 구조가 같은지 판정하는 문제임
- 정지 문제(Halting Problem): 임의 프로그램의 종료 여부를 일반 알고리즘으로 판정할 수 없는 문제임
- 휴리스틱(Heuristic): 경험 규칙으로 실용적인 해를 찾지만 품질을 보장하지 않는 방법임

## 작성 근거(검토용)

- **방향성**: P vs NP는 해의 검증과 해결이 근본적으로 다른 난이도인지 묻는 문제이므로, 시스템은 최적해 탐색에 시간 제한을 걸어 초과 시 근사·휴리스틱으로 전환하고 후보 검증은 별도의 빠른 동기 경로로 분리해 설계해야 함
- **Ⅰ. 개요 구성**: 해결과 검증의 차이를 정의에 포함해 P vs NP의 질문을 직접 드러냄
- **Ⅱ. 특징 선정**: 포함 관계, 검증 의미, NP-완전, P=NP 영향을 답안의 핵심 논리 축으로 선정함
- **Ⅲ. 비교축 선정**: P·NP·NP-완전·NP-난해는 해결·검증·환원 조건에 따른 집합 포함관계 분류이고 상호 배타적 선택지가 아니므로 적용 기준 축을 두지 않고 분류 조건·집합 관계·대표 문제로 경계를 구분함
- **Ⅳ. 구조 선정**: 구조 도식은 P, NP, NP-완전, NP-난해의 포함·교집합 관계를 한 화면에 제시함
- **Ⅴ. 절차 선정**: NP-완전성 증명의 핵심인 다항 시간 환원 절차를 단계로 분해해 순서가 판정 결과를 바꾸는 원리를 보여줌
- **Ⅵ·Ⅶ. 사례·결론 선정**: 배포 스케줄링과 패키지 의존성 해석은 복잡도 이론이 시스템 설계로 이어지는 대표 사례임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 미리 알고가기의 영문 병기·휴리스틱 정의를 보강했으며 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: P vs NP는 다항 시간에 검증 가능한 모든 결정 문제가 다항 시간에 해결 가능한지 묻는 계산 복잡도 난제임
- **배경/필요성**: 최적화·스케줄링·암호 안전성의 해법을 설계하기 위해 계산 난이도 경계의 이해가 필요함

### 쉽게 이해하기 (학습용)
- 완성된 스도쿠가 맞는지 확인하기는 금방이지만, 빈 스도쿠를 항상 빠르게 채우는 방법이 있는지는 아직 아무도 증명하지 못했으며, 이 질문 자체가 P vs NP임

## Ⅱ. 특징

- $P \subseteq NP$는 성립하지만 $P=NP$인지는 증명되지 않음
- NP 문제는 정답 후보를 다항 시간에 검증할 수 있다는 뜻이며 다항 시간 해법을 의미하지 않음
- NP-완전은 NP 안에서 모든 NP 문제가 환원되는 대표 난도 기준임
- P=NP가 증명되면 많은 최적화·암호 전제가 바뀜

### 쉽게 이해하기 (학습용)
- 검증이 쉬운 문제 집합(NP) 안에 해결도 쉬운 문제 집합(P)이 포함된다는 것은 알려졌지만, 둘이 완전히 같은 집합인지는 여전히 모름
- 답 후보가 맞는지 빠르게 확인할 수 있다는 뜻이지, 그 답을 빠르게 찾아낼 수 있다는 뜻은 아님
- 모든 검증 쉬운 문제가 해결도 쉽다는 게 증명되면, 지금까지 어렵다고 믿어온 여러 문제의 전제가 한꺼번에 무너짐

## Ⅲ. 종류 및 비교

| 판단 기준 | P | NP | NP-완전 | NP-난해 |
|:---|:---|:---|:---|:---|
| 분류 조건 | 다항 시간 해결 | 다항 시간 검증 | NP 소속 + NP-난해 | 모든 NP 문제 환원 |
| 집합 관계 | $P \subseteq NP$ | P·NP-완전 포함 | $NP \cap NP\text{-난해}$ | NP 밖 포함 가능 |
| 대표 문제 | 그래프 연결성 | 그래프 동형 | 3-SAT | 정지 문제 |

> 요약: P는 다항 시간 해결 가능, NP는 다항 시간 검증 가능, NP-완전은 NP의 난도 기준, NP-난해는 NP 밖의 문제까지 포함할 수 있음.

### 쉽게 이해하기 (학습용)
- P는 스스로 빠르게 풀 수 있는 문제, NP는 남이 준 답이 맞는지만 빠르게 확인할 수 있는 문제, NP-완전은 그중 가장 어려운 대표 문제, NP-난해는 검증조차 안 되더라도 어려움만은 그 이상인 문제임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 결정론적 알고리즘 | 상태별 다음 동작이 하나인 계산 모델 |
| 검증기 | 답 후보를 다항 시간에 확인하는 알고리즘 |
| 인증서 | 검증기가 확인하는 답 후보·증거 |
| 다항 시간 환원 | 기존 난제를 대상 문제로 바꾸는 변환 |

```text
[ P != NP 가정의 관계 ]
NP      : [ P ] [ NP-완전 ] [ 그 밖의 NP ]
NP-난해 :       [ NP-완전 ] [ NP 밖의 NP-난해 ]
```

> 요약: P, NP, NP-완전, NP-난해의 관계는 해결·검증·환원 조건으로 구분됨.

### 쉽게 이해하기 (학습용)
- 네 그룹을 그림으로 그리면 P는 NP 안에 완전히 들어가고, NP-완전은 NP와 NP-난해가 겹치는 자리에 있으며, NP-난해는 NP 바깥까지 더 넓게 걸쳐 있음

## Ⅴ. 원리 및 절차 흐름도

```text
NP 소속 확인 -> 기존 난제 선정 -> 환원 함수 설계 -> 보존 검증 -> 완전성 판정
```

1. **NP 소속 확인**: 증명 대상 문제의 해 후보를 다항 시간에 확인하는 검증기를 제시함
2. **기존 난제 선정**: 3-SAT처럼 NP-완전으로 증명된 기존 난제를 환원 시작점으로 선정함
3. **환원 함수 설계**: 기존 난제 인스턴스를 증명 대상 문제 인스턴스로 바꾸는 다항 시간 함수를 설계함
4. **보존 검증**: 기존 난제의 충족 여부와 변환된 인스턴스의 해 존재 여부가 항상 일치함을 검증함
5. **완전성 판정**: 위 조건이 성립하면 증명 대상 문제를 NP-완전으로 판정함

> 요약: NP 소속을 확인한 뒤 기존 난제를 다항 시간 환원으로 대상 문제와 연결하고 참·거짓 보존을 검증하면 NP-완전으로 판정됨.

### 쉽게 이해하기 (학습용)
- 새 문제가 답 후보를 빠르게 확인할 수 있는지 먼저 보고, 이미 어렵다고 인정된 문제를 이 새 문제로 바꿔치기하는 절차를 만든 뒤, 그 바꿔치기가 정답 여부를 그대로 유지하는지 확인하면 새 문제도 같은 급으로 어렵다고 인정됨

## Ⅵ. 실무 사례

1. 배포 작업 스케줄러는 정확한 최적 배치 탐색이 제한 시간을 넘으면 휴리스틱 결과를 반환함
2. 패키지 관리 플랫폼은 SAT 해석기로 호환되는 패키지 버전 조합을 찾음

### 쉽게 이해하기 (학습용)
- 최적의 배치를 끝까지 찾다가 시간이 다 되면 일단 그럴듯한 답으로 타협하고, 여러 조건이 얽힌 조합을 찾을 때는 정답 후보를 빠르게 확인하는 도구를 대신 활용함

## Ⅶ. 결론

- P와 NP 문제는 정답 검증과 정답 탐색의 난이도가 다를 수 있음을 묻는 난제이므로, 최적해 탐색은 시간 제한을 넘으면 근사·휴리스틱으로 전환해야 함
- 시스템은 해 탐색과 후보 검증을 같은 SLA로 묶지 말고, 탐색은 비동기·시간 제한 작업으로, 검증은 빠른 동기 경로로 분리해야 함

### 쉽게 이해하기 (학습용)
- 완벽한 답을 찾는 일과 주어진 답이 맞는지 확인하는 일은 걸리는 시간이 전혀 다를 수 있으므로, 이 둘을 같은 기준으로 묶어 처리하면 안 됨
