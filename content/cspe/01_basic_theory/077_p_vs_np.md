## 미리 알고가기

- P: 다항 시간에 풀 수 있는 결정 문제 집합임
- NP: 해답이 주어지면 다항 시간에 검증 가능한 문제 집합임
- NP-완전: NP에 속하면서 모든 NP 문제로부터 환원 가능한 문제임

## Ⅰ. 개요

- **정의/개념**: P vs NP 문제는 해를 빠르게 찾을 수 있는 문제 집합과 해를 빠르게 검증만 할 수 있는 문제 집합이 같은지 묻는 계산복잡도 이론의 핵심 난제임
- **배경/필요성**: 최적화, 검색, 암호, 스케줄링 문제의 본질적 난도를 이해하려면 문제를 계산 가능성뿐 아니라 계산 비용 기준으로 구분해야 함

## Ⅱ. 특징

- 단순 속도 문제가 아니라 계산 모델에서의 구조적 난도 문제임
- NP-완전 문제가 다항 시간에 풀리면 광범위한 최적화 문제가 재정의됨
- 현재까지는 $P \neq NP$로 추정되지만 증명은 없음
- 실무에서는 정확해 대신 근사, 휴리스틱, 제한 조건 완화가 주로 사용됨

## Ⅲ. 종류 및 비교

| 판단 기준 | P | NP | NP-완전 |
|:---|:---|:---|:---|
| 해 찾기 | 다항 시간 가능 | 미확인 | 보통 어려움 |
| 해 검증 | 다항 시간 가능 | 다항 시간 가능 | 다항 시간 가능 |
| 대표 문제 | 최단 경로 | SAT(검증 관점) | 3-SAT, TSP 결정형 |
| 실무 의미 | 정확해 가능 | 제한적 | 근사/휴리스틱 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 계산 모델 | 튜링 머신 기반 복잡도 기준이며 이론적 비교 축임 |
| 환원 | 한 문제를 다른 문제로 변환하고 난도 전파 도구임 |
| 검증 절차 | 해답의 올바름을 확인하고 NP 정의 핵심임 |
| 문제 클래스 | P, NP, NP-hard, NP-complete 등이며 알고리즘 전략을 구분함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문제정의 | --> | 검증가능성 분석 | --> | 환원분석 | --> | 난도분류 |
+----------+     +----------+     +----------+     +----------+
```

1. **문제정의**: 결정 문제 형태로 정식화함
2. **검증가능성 분석**: 주어진 해를 빠르게 확인할 수 있는지 봄
3. **환원분석**: 기존 난문제와 변환 관계를 찾음
4. **난도분류**: P, NP, NP-완전 여부를 판단함

## Ⅵ. 문제점 및 해결 방안

1. **이론 문제를 실무 그대로 오해하기 쉬움**: 평균 사례와 최악 사례를 혼동할 수 있음
   - **해결 방안**: 입력 규모와 실제 제약을 분리해 분석하고 empirical complexity로 검증함
2. **정확 알고리즘 집착이 비효율적일 수 있음**: NP-완전 문제는 실용 시간이 불가능할 수 있음
   - **해결 방안**: 근사, 휴리스틱, 메타휴리스틱을 채택하고 solution quality vs time로 검증함
3. **환원 증명 이해가 어려움**: 문제 난도 판단을 잘못할 수 있음
   - **해결 방안**: 표준 NP-완전 문제 집합을 기준으로 학습하고 reduction correctness로 검증함

## Ⅶ. 적용 사례

- 스케줄링과 배차: 대규모 조합 최적화 문제를 다룸, 확인 지표는 계산시간과 근사비임
- 회로 배치/라우팅: 정확해보다 휴리스틱을 사용함, 확인 지표는 배선 품질임
- 암호 이론: 어려운 문제 기반 보안 가정을 사용함, 확인 지표는 공격 비용 추정임

## Ⅷ. 결론

P vs NP의 핵심은 이론적 증명보다 어떤 문제에 정확해를 포기할지 판단하는 데 있으므로, 난도 분류는 알고리즘 선택의 출발점으로 봐야 함.
