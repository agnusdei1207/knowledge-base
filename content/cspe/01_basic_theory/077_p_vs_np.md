## 미리 알고가기

- 결정 문제: 답이 `예/아니오`로 표현되는 문제이며 복잡도 이론의 기본 분석 대상임
- 다항 시간: 입력 크기 `n`에 대해 `n^k` 꼴 시간 안에 해결되는 시간 범위임
- P: 결정론적 계산 모델에서 다항 시간에 풀 수 있는 문제 집합임
- NP: 후보 해가 주어지면 다항 시간에 검증할 수 있는 결정 문제 집합임
- 환원: 한 문제를 다른 문제로 다항 시간에 변환해 난이도 관계를 보이는 방법임
- NP-Complete: NP에 속하면서 모든 NP 문제가 다항 환원되는 핵심 난제 집합임

## Ⅰ. 개요

- **정의**: P vs NP 문제는 다항 시간에 답을 검증할 수 있는 모든 문제가 다항 시간에 직접 해결될 수도 있는지를 묻는 계산복잡도 이론의 핵심 미해결 문제임. 문제 해결 가능성과 검증 가능성의 차이를 기준으로 알고리즘 선택, 암호 안전성, 최적화 전략을 판단하기 위해 사용함
- **배경/필요성**: 물류, 스케줄링, 회로 설계, 암호 등 많은 실무 문제는 해가 맞는지 확인은 쉽지만 최적해를 찾기 어려우므로 문제 난이도 분류가 필요함
- **비유**: 완성된 스도쿠 답이 맞는지 검사하는 일은 빠르지만, 빈 스도쿠를 처음부터 푸는 일은 훨씬 어려울 수 있는 차이와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| P, NP 관계 설명 | `P ⊆ NP`, 동치 여부 미해결 | NP를 풀 수 없는 문제로 오해 |
| NP-Complete 증명 설명 | NP 소속과 다항 환원 | 환원 방향 혼동 |

> 요약: P vs NP는 검증이 쉬운 문제를 항상 쉽게 풀 수 있는지 묻고, NP-Complete는 그 경계에 있는 대표 문제군임

## Ⅱ. 특징/비교

| 판단 기준 | P | NP | NP-Hard / NP-Complete |
|:---|:---|:---|:---|
| 핵심 의미 | 다항 시간에 직접 해결 가능함 | 후보 해를 다항 시간에 검증 가능함 | NP 문제들이 다항 환원될 만큼 어려움 |
| 포함 관계 | NP에 포함됨 | P를 포함하지만 P와 같은지는 미해결임 | NP-Complete는 NP와 NP-Hard의 교집합임 |
| 대표 문제 | 최단 경로, MST, 정렬 판정 | SAT, Hamiltonian cycle 후보 검증 | SAT, 3-SAT, TSP 결정형 |
| 전략 기준 | 정확한 다항 알고리즘 사용 | 검증기와 탐색 전략 구분 | 근사, 휴리스틱, 특수 케이스 활용 |

> 요약: P는 해결 가능성, NP는 검증 가능성, NP-Complete는 NP 전체 난이도를 대표하는 환원 중심 개념임

- **P=NP라면**: 많은 탐색·최적화 문제가 다항 시간 해법을 가질 수 있어 암호와 최적화의 기반이 흔들림
- **P≠NP라면**: 정확해 대신 근사 알고리즘, 휴리스틱, 제한된 입력에 대한 특수 알고리즘이 중요해짐
- **실무 기준**: 문제를 먼저 결정형으로 바꾸고 난이도 분류 후 해법 전략을 정해야 함

## Ⅲ. 구성요소

```text
+---------------------------------------------+
|                    NP                       |
|   +-----------+      +-------------------+   |
|   |     P     | ---> |   NP-Complete     |   |
|   | solvable  |      | SAT, 3-SAT       |   |
|   +-----------+      +---------+---------+   |
|                                |             |
|                                v             |
|                         +-------------+      |
|                         | NP-Hard     |      |
|                         | may not NP  |      |
|                         +-------------+      |
+---------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 결정 문제 | 답을 예/아니오로 바꿔 복잡도 분류와 환원을 가능하게 한 문제임 | 판정 시험 |
| P 클래스 | 다항 시간 알고리즘으로 직접 풀 수 있는 문제 집합임 | 바로 풀이 |
| NP 클래스 | 정답 후보의 타당성을 다항 시간에 검증할 수 있는 문제 집합임 | 빠른 채점 |
| 다항 환원 | 알려진 어려운 문제를 새 문제로 변환해 새 문제도 어렵다는 근거를 제공함 | 난이도 이전 |
| NP-Complete | NP에 속하면서 모든 NP 문제가 환원되는 최난도 대표 문제군임 | 관문 문제 |

> 요약: P vs NP 구조는 결정 문제, 검증기, 다항 환원, NP-Complete 문제군을 통해 문제 난이도를 분류함

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Formalize | --> | Verify    | --> | Reduce    | --> | Choose    |
| Decision  |     | in Poly   |     | Known NPC |     | Strategy  |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
yes/no problem      NP membership      hardness proof     exact/approx
```

1. **문제 정형화**: 최적화 문제를 임계값 기반 결정 문제로 바꾸고 입력 크기와 해의 표현을 명확히 함
2. **NP 소속 증명**: 후보 해가 주어졌을 때 다항 시간에 검증 가능한지 검증 알고리즘을 제시함
3. **다항 환원 증명**: SAT, 3-SAT 등 기존 NP-Complete 문제를 현재 문제로 변환해 난이도 하한을 보임
4. **해법 전략 선택**: P로 풀리면 정확 알고리즘을, NP-Complete라면 근사·휴리스틱·제약 완화를 검토함

> 요약: P/NP 분류는 결정형 정리, 검증 가능성 확인, 환원 증명, 해법 전략 결정 순서로 수행함

## Ⅴ. 문제점

- **P1 탐색 공간 폭증**: NP-Complete 문제는 알려진 일반 다항 알고리즘이 없어 입력 증가 시 후보 해 공간이 급격히 커짐
- **P2 환원 증명 난도**: 실제 문제를 정확히 결정형으로 모델링하고 올바른 방향으로 환원하는 과정이 어렵고 오류가 잦음
- **P3 실무 요구와 이론 격차**: 산업 문제는 최적해가 필요하지만 시간, 데이터, 제약 변화 때문에 이론적 정확해만 기다릴 수 없음

> 요약: P vs NP의 실무 어려움은 계산 폭발, 난이도 증명 복잡성, 이론 한계와 현장 의사결정 사이의 간극임

## Ⅵ. 개선방안

- **P1 대응**: 분기 한정, 동적 계획법, 파라미터화 알고리즘으로 입력 구조를 활용해 탐색을 줄임 (확인: 탐색 노드 수, 실행 시간)
- **P2 대응**: 알려진 NP-Complete 문제 목록과 환원 방향을 명확히 정리하고 작은 예시로 변환 정확성을 검증함 (확인: 환원 함수의 다항성)
- **P3 대응**: 근사 알고리즘, 메타휴리스틱, 제한 시간 최적화, 온라인 재계산 전략을 적용함 (확인: 최적성 gap, SLA 충족률)

> 요약: 이론 분류는 해법 포기를 뜻하지 않으며, 문제 구조와 품질 기준에 맞춰 정확해·근사해·휴리스틱을 선택해야 함

## Ⅶ. 전망

- **발전 방향**: P vs NP 자체는 미해결이지만 SAT/SMT solver, 근사 알고리즘, 양자·확률 알고리즘 연구가 실무 해결력을 넓힐 전망임
- **기술사적 판단**: 복잡한 최적화 요구를 받으면 먼저 P/NP/NP-Hard 성격을 분류하고 품질 보장 수준을 협의해야 함
- **기술사 제언**: 답안에서는 `NP=풀 수 없음` 같은 오해를 피하고 검증 가능성, 환원, 전략 선택의 흐름으로 설명해야 함
