## 미리 알고가기

- 결정 문제: 답이 예 또는 아니오로 표현되는 문제임
- 다항 시간: 수행 시간이 입력 크기의 다항식으로 제한되는 시간 범위임
- 다항 시간 해결 집합(P): 결정론적 알고리즘으로 다항 시간에 풀 수 있는 문제 집합임
- 다항 시간 검증 집합(NP): 답 후보가 주어지면 다항 시간에 검증 가능한 문제 집합임
- NP-완전 문제(NP-Complete): NP에 속하면서 모든 NP 문제가 다항 시간에 환원되는 문제 집합임
- NP-난해 문제(NP-Hard): 모든 NP 문제가 다항 시간에 환원되며 NP 밖의 문제도 포함할 수 있는 집합임
- 환원(Reduction): 한 문제를 다른 문제로 다항 시간에 바꿔 난도를 비교하는 방법임
- 논리식 충족 가능성 문제(SAT): 주어진 논리식을 참으로 만드는 변수 조합이 존재하는지 판정하는 문제임
- 그래프 동형 문제: 두 그래프의 노드 이름이 달라도 연결 구조가 같은지 판정하는 문제임
- 정지 문제: 임의 프로그램의 종료 여부를 일반 알고리즘으로 판정할 수 없는 문제임

## 작성 근거(검토용)

- 개요는 해결과 검증의 차이를 정의에 포함해 P vs NP의 질문을 직접 드러냄
- 특징은 포함 관계, 검증 의미, NP-완전, P=NP 영향을 답안의 핵심 논리 축으로 선정함
- Ⅲ은 분류 조건, 집합 관계, 대표 문제로 복잡도 클래스의 혼동을 줄임
- 구조 도식은 P, NP, NP-완전, NP-난해의 포함·교집합 관계를 한 화면에 제시함
- 클라우드 스케줄링과 패키지 의존성 해석은 복잡도 이론이 시스템 설계로 이어지는 대표 사례임

## Ⅰ. 개요

- **정의/개념**: P vs NP는 다항 시간에 검증 가능한 모든 결정 문제가 다항 시간에 해결 가능한지 묻는 계산 복잡도 난제임
- **배경/필요성**: 최적화·스케줄링·암호 안전성의 해법을 설계하기 위해 계산 난이도 경계의 이해가 필요함

## Ⅱ. 특징

- $P \subseteq NP$는 성립하지만 $P=NP$인지는 증명되지 않음
- NP 문제는 정답 후보를 다항 시간에 검증할 수 있다는 뜻이며 다항 시간 해법을 의미하지 않음
- NP-완전은 NP 안에서 모든 NP 문제가 환원되는 대표 난도 기준임
- P=NP가 증명되면 많은 최적화·암호 전제가 바뀜

## Ⅲ. 종류 및 비교

| 판단 기준 | P | NP | NP-완전 | NP-난해 |
|:---|:---|:---|:---|:---|
| 분류 조건 | 다항 시간 해결 | 다항 시간 검증 | NP 소속 + NP-난해 | 모든 NP 문제 환원 |
| 집합 관계 | $P \subseteq NP$ | P·NP-완전 포함 | $NP \cap NP\text{-난해}$ | NP 밖 포함 가능 |
| 대표 문제 | 그래프 연결성 | 그래프 동형 | 3-SAT | 정지 문제 |

> 요약: P는 다항 시간 해결 가능, NP는 다항 시간 검증 가능, NP-완전은 NP의 난도 기준, NP-난해는 NP 밖의 문제까지 포함할 수 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 핵심 설명 |
|:---|:---|
| 결정론적 알고리즘 | 상태별 다음 동작이 하나인 계산 모델 |
| 검증기 | 답 후보를 다항 시간에 확인하는 알고리즘 |
| 인증서 | 검증기가 확인하는 답 후보·증거 |
| 다항 시간 환원 | 기존 난제를 대상 문제로 바꾸는 변환 |

```text
[ P != NP 가정의 관계 ]
NP      : [ P ] [ NP-완전 ] [ 그 밖의 NP ]
NP-난해 :       [ NP-완전 ] [ NP 밖의 NP-난해 ]
```

> 요약: P, NP, NP-완전, NP-난해의 관계는 해결·검증·환원 조건으로 구분됨.

## Ⅵ. 실무 사례

1. 클라우드 작업 스케줄링은 정확해가 시간 한도를 넘으면 근사·휴리스틱을 적용하고 해 품질·계산 시간으로 검증함
2. 패키지 의존성 해석은 SAT로 모델링하고 해 탐색 시간·후보 해 검증 시간으로 해결·검증 차이를 확인함

## Ⅶ. 결론

- P·NP·NP-완전·NP-난해 구분은 해결·검증·환원 가능성에 따라 해법과 보안 가정을 선택하는 기준임
