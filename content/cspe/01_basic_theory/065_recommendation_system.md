# 📖 【암기용】 개념 완전 이해

> 목적: 추천 시스템을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 추천 시스템은 사용자에게 선택 가능성이 높은 항목을 순위화하는 시스템이다.
- **왜 필요한가**:
  - 상품·콘텐츠·뉴스가 수천~수백만 개이면 사용자는 모두 탐색할 수 없다
  - 추천은 사용자 행동과 항목 정보를 이용해 탐색 비용을 줄이고 전환율을 높인다
- **핵심 직관**: 내가 좋아한 항목과 비슷한 항목, 또는 나와 비슷한 사용자가 좋아한 항목을 먼저 보여주는 방식이다.

## 깊이 이해
- **배경·문제의식**:
  - 검색은 사용자가 명시적 질의를 입력해야 하지만 추천은 클릭·구매·시청 같은 암묵 행동에서 선호를 추정한다
  - 데이터 희소성, 콜드스타트, 다양성 부족이 핵심 문제이다
- **작동 원리**:
  - 협업 필터링은 사용자-항목 상호작용 행렬을 사용한다
  - 콘텐츠 기반 추천은 항목 속성과 사용자 프로필을 비교한다
  - 실제 서비스는 후보 생성, 랭킹, 재정렬 3단계로 구성한다
- **비유**: 협업 필터링은 취향이 비슷한 친구의 선택을 참고하는 방식이고, 콘텐츠 기반은 내가 본 영화의 장르·배우와 비슷한 영화를 찾는 방식이다.
- **구체 예시**: 전자상거래에서 후보 생성은 최근 구매자 유사도 Top 500개 상품을 뽑고, 랭킹 모델은 가격·재고·CTR 예측으로 Top 20을 정렬한다.
- **흔한 오해·주의점**:
  - 추천 정확도만 높이면 충분하지 않다
  - 다양성, 신선도, 공정성, 필터버블, 개인정보 보호를 함께 설계해야 한다

## 연결 개념
- 협업 필터링: 사용자-항목 행렬 기반 추천
- 행렬 분해: 잠재 요인 기반 선호 추정
- 랭킹 모델: 후보를 클릭·구매 확률 순으로 정렬

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 추천 시스템은 사용자·항목·상호작용 데이터를 이용해 개인별 후보를 생성하고 순위를 매기는 의사결정 시스템이다.
> 2. **가치**: 탐색 비용을 줄이고 CTR, CVR, 재방문율 같은 서비스 지표를 개선한다.
> 3. **판단 포인트**: 협업 필터링, 콘텐츠 기반, 하이브리드 방식을 데이터 희소성·콜드스타트·지연시간 기준으로 선택한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 사용자에게 선택 가능성이 높은 항목을 순위화하는 개인화 시스템
- 배경: 대규모 상품·콘텐츠 환경에서는 사용자가 전체 항목을 직접 비교할 수 없어 탐색 비용과 이탈률이 증가함
- 필요성: 행동 로그와 항목 속성을 결합해 후보 생성, 랭킹, 재정렬 단계로 사용자별 Top-N 항목을 제공함

---

## Ⅱ. 구조 및 구성요소

```text
사용자 로그/항목 정보 -> 특징 저장소 -> 후보 생성 -> 랭킹 모델 -> 재정렬 -> Top-N 추천
                                      +-> 정책 필터 -> 다양성/신선도 통제
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 사용자 프로필 | 클릭·구매·시청 이력 표현 | 최근성 가중치, 세션 특징 |
| 항목 특징 | 카테고리·텍스트·가격·재고 표현 | 콘텐츠 기반 추천 입력 |
| 후보 생성 | 수백만 항목을 수백 개로 축소 | CF, ANN, popularity |
| 랭킹·재정렬 | CTR/CVR 예측 후 정책 반영 | 다양성, 공정성, 비즈니스 룰 |

> 요약: 추천 시스템은 사용자·항목 특징을 기반으로 후보를 줄이고 랭킹과 재정렬로 Top-N 결과를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그 수집 -> 특징 생성 -> 후보 생성 -> 랭킹 점수 계산 -> 정책 재정렬 -> 노출/피드백
            +-> 온라인 A/B 테스트 -> 모델 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 클릭·구매·평점·시청 로그 수집 | 이벤트 누락률 1% 이하 |
| 2 | 사용자·항목·컨텍스트 특징 생성 | feature freshness 5분~1일 |
| 3 | 협업/콘텐츠 기반 후보 생성 | Recall@100, coverage |
| 4 | 랭킹·A/B 테스트·피드백 반영 | CTR, CVR, NDCG@10 |

> 요약: 추천은 로그 수집에서 후보 생성과 랭킹을 거쳐 사용자 반응을 다시 학습 데이터로 반영하는 폐루프 구조이다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 개인별 Top-N 제공으로 탐색 비용 감소 | CTR 5%p, CVR 2%p 개선 목표 |
| 한계 | 콜드스타트·데이터 희소성·필터버블 | 신규 사용자·신규 항목 비율 |
| 비교 대상 | 검색, 인기순, 규칙 기반 노출 | 질의 유무와 개인화 수준 |
| 수치 기준 | Recall@100, NDCG@10, p95 100ms | 오프라인+온라인 A/B 병행 |

> 요약: 추천 시스템은 개인화 지표 개선 효과가 있으나 콜드스타트와 편향을 별도 통제해야 한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 인기순은 전체 동일 노출 | 추천은 사용자별 순위 생성 | 개인화 로그 1만 건 이상 |
| 비용/성능 | 콘텐츠 기반은 신규 항목 대응 | 협업 필터링은 행동 유사도 반영 | 콜드스타트 비율 기준 |
| 운영/위험 | 검색은 사용자 질의 필요 | 추천은 무질의 탐색 제공 | 홈·피드·상품상세 영역 |

> 요약: 행동 로그가 충분하면 협업 필터링, 신규 항목이 많으면 콘텐츠 기반, 서비스 규모가 크면 하이브리드를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 콜드스타트 | 신규 사용자·항목 로그 부족 | 콘텐츠 특징, 인기순 fallback | 신규 항목 노출률 10% 이상 |
| 필터버블 | 유사 항목 반복 노출 | 다양성 재정렬, 탐색 슬롯 | 카테고리 다양성 지수 |
| 개인정보 침해 | 행동 로그 과다 수집 | 가명처리, 동의관리, 접근통제 | 감사로그 100% 기록 |

> 요약: 추천 리스크는 콜드스타트, 편향, 개인정보를 fallback·재정렬·접근통제로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 추천 품질 | NDCG@10 0.35 이상, Recall@100 0.60 이상 | 오프라인 평가 |
| 온라인 효과 | CTR 5%p 상승, CVR 2%p 상승 | A/B 테스트, CUPED |
| 운영 지연 | 후보 생성+랭킹 p95 100ms 이하 | APM, 부하테스트 |

> 요약: 추천 시스템은 오프라인 랭킹 품질, 온라인 전환 효과, p95 지연시간을 함께 만족해야 한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 1단계는 인기순+콘텐츠 기반 fallback으로 콜드스타트를 처리하고 신규 항목 노출률 10% 이상을 확보함
2. 2단계는 협업 필터링 또는 행렬분해로 Recall@100 0.60 이상 후보 생성기를 구축함
3. 3단계는 랭킹 모델과 다양성 재정렬을 적용하고 A/B 테스트로 CTR 5%p, CVR 2%p 개선 여부를 검증함

**결론 (2줄):**
- 기술사 판단: 로그가 적으면 콘텐츠 기반, 행동 로그가 충분하면 협업 필터링, 대규모 서비스는 하이브리드를 선택함
- 향후 방향: 추천 시스템은 실시간 피처 저장소, ANN 검색, 공정성 제약, 개인정보 보호 학습과 결합해 고도화됨
