## 미리 알고가기

- 명시적 피드백: 평점, 좋아요처럼 사용자가 직접 선호를 표현한 데이터임
- 암시적 피드백: 클릭, 구매, 체류 시간처럼 행동 로그에서 추정한 선호 신호임
- 협업 필터링: 사용자-아이템 상호작용 패턴이 비슷한 대상을 기준으로 추천함
- 콘텐츠 기반 필터링: 아이템 속성과 사용자 프로필의 유사도를 기준으로 추천함
- 행렬 분해: 사용자와 아이템을 잠재 요인 벡터로 분해해 미관측 선호를 예측함
- 콜드 스타트: 신규 사용자나 신규 아이템의 상호작용 데이터가 부족해 추천이 어려운 상태임

## Ⅰ. 개요

- **정의**: 추천 시스템은 사용자 행동과 아이템 속성을 분석해 선호 가능성이 높은 대상을 점수화·순위화하는 개인화 정보 필터링 시스템임
- **배경/필요성**: 콘텐츠와 상품 수가 급증하면 사용자가 직접 탐색하기 어렵고, 플랫폼은 개인별 관심사에 맞춘 노출 전략이 필요해짐
- **비유**: 단골의 취향과 주변 고객의 선택을 함께 보고 다음에 좋아할 메뉴를 미리 추천하는 직원과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 추천 방식 비교 | 협업 필터링, 콘텐츠 기반, 하이브리드 | 콜드 스타트 원인 누락 |
| 품질 평가 관점 설명 | 정확도, 다양성, 신선도, 편향 | CTR만으로 품질 설명 |

> 요약: 추천 시스템은 사용자와 아이템 간의 관측·비관측 선호를 예측해 개인별 Top-N 목록을 만드는 의사결정 시스템임

## Ⅱ. 특징/비교

| 판단 기준 | 협업 필터링 | 콘텐츠 기반 | 하이브리드 |
|:---|:---|:---|:---|
| 추천 기준 | 유사 사용자 또는 유사 아이템의 행동 패턴 | 아이템 속성과 사용자 프로필 유사도 | 행동과 속성 정보를 함께 사용 |
| 강점 | 취향 패턴과 잠재 선호를 포착함 | 신규 아이템 속성만으로도 추천 가능함 | 단일 방식의 약점을 보완함 |
| 약점 | 콜드 스타트와 희소 행렬에 취약함 | 유사한 아이템만 반복 추천될 수 있음 | 설계와 운영 복잡도가 증가함 |
| 선택 조건 | 상호작용 로그가 충분할 때 | 메타데이터 품질이 높을 때 | 로그와 콘텐츠 정보가 모두 의미 있을 때 |

> 요약: 추천 방식은 사용 가능한 데이터가 행동 로그인지, 아이템 속성인지, 두 정보의 결합인지에 따라 선택함

- **랭킹 기준**: 예측 평점뿐 아니라 클릭 확률, 구매 확률, 다양성, 비즈니스 제약을 함께 반영함
- **운영 기준**: 오프라인 지표가 좋아도 A/B 테스트에서 사용자 반응을 확인해야 함
- **통제 기준**: 인기 편향, 필터 버블, 부적절 추천을 완화하는 정책을 포함해야 함

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| User Logs   | ---> | Feature /   | ---> | Candidate   |
| Ratings     |      | Matrix      |      | Generator   |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Item Meta   | ---> | Ranker      | ---> | Top-N       |
| Content     |      | Scoring     |      | Recommend   |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 사용자 로그 | 클릭, 구매, 평점, 체류 시간 등 선호를 추정하는 원천 데이터임 | 발자국 |
| 아이템 메타데이터 | 장르, 카테고리, 가격, 키워드 등 콘텐츠 기반 추천의 입력임 | 상품 설명서 |
| 후보 생성기 | 대규모 아이템 중 추천 후보 수백~수천 개를 빠르게 줄이는 단계임 | 1차 선별 |
| 랭킹 모델 | 후보를 사용자별 점수로 정렬해 최종 노출 순서를 결정함 | 심사위원 |
| 피드백 루프 | 노출 후 반응을 다시 수집해 모델과 정책을 갱신함 | 학습 기록장 |

> 요약: 추천 시스템은 로그와 메타데이터를 기반으로 후보를 만들고 랭킹한 뒤 사용자 반응을 다시 학습하는 폐루프 구조임

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Collect   | --> | Build     | --> | Score     | --> | Serve     |
| Feedback  |     | Profile   |     | Rank      |     | & Learn   |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
logs/events        user-item matrix    top-N list        new feedback
```

1. **피드백 수집**: 명시적·암시적 행동을 수집하고 부정 클릭, 중복 이벤트, 봇 트래픽을 정제함
2. **표현 구축**: 사용자-아이템 행렬, 잠재 요인, 아이템 임베딩, 사용자 프로필을 생성함
3. **후보 생성·랭킹**: 협업 필터링, 콘텐츠 유사도, 딥러닝 랭커로 후보별 점수를 계산하고 정렬함
4. **서빙·학습**: Top-N을 노출하고 클릭률, 전환율, 재방문율, 다양성 지표를 모니터링해 재학습함

> 요약: 추천 절차는 사용자 반응을 표현으로 바꾼 뒤 후보를 점수화하고 운영 반응으로 다시 개선하는 반복 구조임

## Ⅴ. 문제점

- **P1 콜드 스타트**: 신규 사용자·아이템은 상호작용 로그가 부족해 협업 필터링 기반 점수의 신뢰구간이 넓어짐
- **P2 데이터 희소성과 인기 편향**: 대부분의 사용자-아이템 조합이 비어 있고 인기 아이템만 반복 노출되어 다양성이 낮아짐
- **P3 실시간 문맥 반영 부족**: 계절, 위치, 세션 의도 같은 현재 맥락을 반영하지 못하면 추천 적시성이 떨어짐

> 요약: 추천 품질은 데이터가 부족한 대상, 희소한 상호작용, 현재 의도 미반영에서 먼저 흔들림

## Ⅵ. 개선방안

- **P1 대응**: 온보딩 질문, 인기도 기반 폴백, 콘텐츠 기반 초기 추천을 결합함 (확인: 신규 사용자 7일차 유지율)
- **P2 대응**: 행렬 분해, negative sampling, 다양성 제약, 탐색-활용 정책을 적용함 (확인: NDCG와 catalog coverage)
- **P3 대응**: 세션 기반 모델, 시간 감쇠 가중치, 실시간 피처 저장소로 현재 의도를 반영함 (확인: 세션 CTR과 전환율)

> 요약: 콜드 스타트는 초기 정보로, 희소성은 잠재 표현과 다양성 정책으로, 문맥 문제는 실시간 피처로 대응함

## Ⅶ. 전망

- **발전 방향**: 대화형 추천, 지식 그래프, 멀티모달 임베딩이 결합되어 사용자의 명시 의도와 암시 행동을 함께 반영할 전망임
- **기술사적 판단**: 추천 시스템은 정확도 경쟁을 넘어 공정성, 설명 가능성, 개인정보 보호가 품질 기준에 포함되는 방향으로 진화함
- **기술사 제언**: 답안에서는 협업·콘텐츠·하이브리드 비교와 함께 콜드 스타트 및 편향 대응을 반드시 연결해야 함
