# 📖 【암기용】 개념 완전 이해

> 목적: 추천 시스템을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **협업 필터링**(Collaborative Filtering)과 **콘텐츠 기반 필터링**(Content-Based Filtering)을 두 축으로 삼아, 사용자가 아직 경험하지 않은 아이템에 대한 선호도를 예측해 제안하는 시스템이 추천 시스템이다.
- **왜 필요한가**: 유튜브 영상, 넷플릭스 영화, 쇼핑몰 상품처럼 아이템 수가 사용자가 다 둘러볼 수 없을 만큼 많아지면(정보 과부하), 사용자가 직접 검색하기 전에 좋아할 만한 것을 먼저 제시해야 이탈을 막을 수 있다.
- **핵심 직관**: "너와 취향이 비슷한 사람이 산 물건"을 권하는 게 협업 필터링, "네가 예전에 산 물건과 속성이 비슷한 물건"을 권하는 게 콘텐츠 기반이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 협업 필터링(CF) | 다수 사용자의 행동(평점·클릭) 패턴만으로 취향이 비슷한 사용자·아이템을 찾아 추천 — 아이템 내용은 몰라도 됨 | 취향이 같은 친구가 듣는 노래를 따라 듣기 |
| 콘텐츠 기반 필터링(CBF) | 아이템의 속성(장르·감독·키워드)을 분석해, 사용자가 좋아한 아이템과 속성이 비슷한 것을 추천 | SF 영화 마니아에게 다른 SF 영화 권하기 |
| 명시적 피드백 | 사용자가 직접 남긴 평점·별점처럼 선호를 확실히 아는 신호 | 설문지에 직접 점수 매기기 |
| 암시적 피드백 | 클릭·체류시간·구매 이력처럼 선호를 간접적으로 추정하는 신호 | 어느 매대 앞에 오래 서 있었는지 관찰 |
| 사용자-아이템 행렬 | 행=사용자, 열=아이템, 값=평점(또는 클릭 여부)으로 이루어진 표 — CF의 기본 데이터 구조 | 반 전체 학생이 영화마다 매긴 평점표 |
| 코사인 유사도 | 두 벡터(사용자 또는 아이템)의 방향이 얼마나 비슷한지를 −1~1로 측정 | 두 화살표가 같은 방향을 가리키는 정도 |
| 행렬 분해(Matrix Factorization, SVD) | 거대한 사용자-아이템 행렬을 "사용자 특성 행렬 × 아이템 특성 행렬"의 곱으로 근사 분해해 빈칸을 채움 | 큰 표를 몇 개의 숨은 성향 축으로 압축 요약 |
| 잠재 요인(Latent Factor) | 행렬 분해로 얻어지는, 명시적으로 이름 붙지 않은 숨은 취향 축(예: "액션 성향", "감성 성향") | 겉으로 안 보이지만 실제로 취향을 가르는 숨은 기준 |
| Cold Start | 신규 사용자·아이템은 행동 기록이 없어 추천할 근거가 없는 문제 | 전학 온 첫날, 아직 아무도 그 학생을 모름 |
| Sparsity(희소성) | 사용자 수 × 아이템 수에 비해 실제 평점이 극히 일부만 채워져 행렬 대부분이 빈칸인 상태 | 반 전체 시험지에서 대부분 문제가 백지 |
| 하이브리드 | CF와 CBF를 결합해 서로의 약점(Cold Start ↔ 취향 다양성 부족)을 보완 | 두 조언을 같이 듣고 결정 |

## 깊이 이해

### 협업 필터링 — 사용자-아이템 행렬과 코사인 유사도로 직접 계산해보기
- 영화 4편에 대한 평점(1~5, 0은 미평가): 사용자 A=[5, 4, 0, 1], 사용자 B=[5, 5, 0, 1], 사용자 C=[1, 1, 0, 5].
- A와 B는 방향이 거의 같아 코사인 유사도가 1에 가깝고(둘 다 1·2번 영화를 좋아하고 4번을 싫어함), A와 C는 방향이 달라 유사도가 낮다.
- B가 아직 안 본 3번 영화를 A가 좋아했다고 가정하면, 유사도가 높은 A의 평점을 근거로 B에게도 3번 영화를 추천한다 — 이것이 사용자 기반(User-based) CF의 원리다.

### 행렬 분해로 빈칸 채우기 — 잠재 요인 수치 예시
- 사용자-아이템 행렬 R을 사용자 행렬 P(사용자 × 잠재요인 2개)와 아이템 행렬 Q(아이템 × 잠재요인 2개)의 곱으로 근사한다고 하자.
- 사용자 A의 잠재 벡터가 [액션성향=0.9, 로맨스성향=0.1], 영화 X의 잠재 벡터가 [액션성향=0.8, 로맨스성향=0.2]라면, 예측 평점은 두 벡터의 내적(0.9×0.8 + 0.1×0.2=0.74)을 스케일링해 산출한다 — A는 액션 성향이 강하고 X도 액션 성향이 강하므로 높은 평점이 예측된다.
- 이 잠재요인은 사람이 "액션성향"이라 이름 붙이지 않아도 학습 과정에서 자동으로 발견된다. 이렇게 압축하면 원본 행렬의 빈칸(미평가)도 P×Q로 채울 수 있어 Sparsity 문제가 완화된다.

### Sparsity 문제 — 수치로 체감하기
- 사용자 100만 명, 아이템 10만 개면 행렬 칸 수는 100만×10만=1,000억 칸이다. 실제 평점이 1억 건 쌓였다면 밀도는 1억/1,000억=0.1%에 불과하다 — 99.9%가 빈칸이라 단순 유사도 계산조차 근거 데이터가 부족해진다.
- 행렬 분해는 이 1,000억 칸을 직접 다루지 않고, 100만×k와 10만×k(k=잠재요인 수, 예: 50)로 압축해 계산량을 자릿수 단위로 줄이면서 동시에 빈칸을 추정해낸다.

### Cold Start — 왜 생기고 어떻게 우회하나
- 신규 가입자는 평점 이력이 0건이므로 사용자-아이템 행렬에서 그 행이 전부 빈칸이다. CF는 "비슷한 사용자"를 찾을 근거 자체가 없어 추천이 불가능하다.
- 우회책: 가입 시 좋아하는 장르 3~5개를 직접 고르게 해(콘텐츠 기반 프로필 생성), 초기 며칠은 CBF로 추천하다가 클릭·평점이 쌓이면 CF 가중치를 점차 높이는 하이브리드 전환을 쓴다. 넷플릭스가 가입 직후 장르를 고르게 하는 것이 이 예다.

### 판별 원리 — CF vs CBF vs 하이브리드
- 사용자 행동 데이터가 충분히 쌓여 있고 정확도가 최우선이면 CF(특히 모델 기반, SVD/딥러닝)를 쓴다.
- 신규 아이템·신규 사용자가 계속 유입되는 서비스라면 CBF 또는 하이브리드로 Cold Start를 방어해야 한다.
- 데이터가 커질수록 메모리 기반 CF(KNN, 실시간 전체 비교)는 예측 시점 연산량이 O(N)으로 늘어나 느려지므로, 모델 기반(SVD 등 사전 학습)으로 전환해 예측을 O(1)에 가깝게 만든다.

## 연결 개념
- 딥러닝 기반 추천(NCF) — 행렬 분해의 내적 연산을 신경망으로 대체해 비선형 상호작용까지 학습
- 차원 축소(SVD) — 거대한 사용자-아이템 행렬의 희소성을 줄이는 행렬 분해 기법
- A/B 테스트 — 추천 알고리즘 변경의 실제 클릭률(CTR) 개선을 검증하는 방법
- 코사인 유사도 — CF의 사용자·아이템 유사도 계산에 쓰이는 핵심 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 추천 시스템은 사용자-아이템 간의 상호작용(명시적/암시적 피드백)을 분석하여 미경험 아이템의 선호도를 예측하는 알고리즘이다.
> 2. **가치**: 정보 과부하를 해소하고, 사용자 체류 시간과 플랫폼의 전환율(Conversion Rate, CTR)을 극대화한다.
> 3. **판단 포인트**: 협업 필터링은 높은 정확도를 가지나 Cold Start와 Sparsity 한계가 있으므로, 콘텐츠 기반 방식과 딥러닝을 결합한 하이브리드 설계가 필수다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 추천 알고리즘의 2대 축 이해와 장단점 비교 | 협업 필터링(CF)과 콘텐츠 기반(CBF)의 작동 원리 대조 | 두 방식의 한계를 섞어서 서술하면 감점 |
| 실제 운영 시 발생하는 한계와 극복 방안 | Cold Start 문제, Sparsity 문제 지적과 하이브리드 극복 방안 | "데이터를 많이 모은다" 같은 추상적 대응 금지 |

> 요약: CF와 CBF의 근본 원리(행렬 vs 속성)를 대조하고, Cold Start 리스크를 방어하는 하이브리드 아키텍처를 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 사용자의 과거 행동이나 아이템 특성을 분석해 선호도를 예측하고 맞춤형 정보를 제공하는 시스템
- 배경: 디지털 플랫폼의 상품/콘텐츠 폭증으로 사용자의 탐색 비용(Search Cost)이 증가함
- 필요성: 개인화 큐레이션을 통해 사용자 이탈을 방지하고 클릭률(CTR)과 교차 판매(Cross-Selling) 매출을 증대시킴

---

## Ⅱ. 구조 및 구성요소

```text
로그 수집 -> 프로파일링(사용자/아이템) -> 추천 알고리즘(CF/CBF) -> 랭킹(Top-N) -> 결과 서빙
             +-> 명시적/암시적 피드백
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 수집기 | 평점(명시적), 클릭/체류시간(암시적) 로그 수집 | 실시간 스트리밍 / 배치 처리 |
| 프로파일러 | 사용자의 취향 벡터 및 아이템 속성 벡터화 | TF-IDF, 임베딩 |
| 추천 엔진 | 선호도 점수(Score) 또는 확률 예측 | 메모리 기반(KNN), 모델 기반(SVD) |
| 랭킹 시스템 | 예측 점수 기반 상위 N개 아이템 정렬 필터링 | 비즈니스 로직(재고, 단가) 반영 |

> 요약: 추천 시스템은 사용자 로그를 프로파일링하여 선호도를 예측한 뒤, 랭킹을 거쳐 최종 아이템을 제공한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
피드백 수집 -> 사용자-아이템 행렬 구축 -> 유사도 계산 -> 미평가 항목 점수 예측 -> Top-N 추천
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 로그(평점, 구매, 클릭) 수집 및 정제 | 암시적 피드백 노이즈 제거 |
| 2 | 행렬(Matrix) 구축 또는 속성 벡터화 | 사용자-아이템 희소 행렬(Sparsity) 처리 |
| 3 | 유사도 산출 (코사인 유사도, 피어슨 상관계수) | 사용자 간(U2U) 또는 아이템 간(I2I) 거리 |
| 4 | 미경험 아이템 예측 평점 산출 및 랭킹 | RMSE, MAE 최소화 |

> 요약: 추천 알고리즘은 평점 행렬을 기반으로 유사도를 계산하여 비어있는 선호도 점수를 예측한다.

## Ⅳ. 특징

| 구분 | 협업 필터링 (CF) | 콘텐츠 기반 필터링 (CBF) |
|:---|:---|:---|
| 원리 | 다수의 사용자 행동 패턴(행렬) 기반 | 아이템 자체의 속성(메타데이터) 기반 |
| 장점 | 아이템 내용 분석 불필요, 의외의 발견(Serendipity) 제공 | 신규 아이템 즉시 추천 가능, 사용자 독립적 |
| 한계 | Cold Start, Sparsity 문제 발생 | 과도한 특화(Filter Bubble), 메타데이터 추출 난이도 |

> 요약: CF는 군중의 지혜를 빌리나 초기 데이터가 필요하고, CBF는 초기 추천이 가능하나 추천의 다양성이 떨어진다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 메모리 기반 CF (KNN) | 모델 기반 CF (SVD, NCF) | 선택 기준 |
|:---|:---|:---|:---|
| 학습 방식 | 전체 행렬을 메모리에 올리고 거리 계산 | 행렬 분해나 신경망으로 가중치 사전 학습 | 데이터 크기 및 실시간 요구 사항 |
| 연산 부하 | 예측 시점(Inference) 연산량 높음 $O(N)$ | 학습 부하는 크나 예측 속도 빠름 $O(1)$ | 100만 명 이상 서비스 시 모델 기반 필수 |
| 확장성 | 희소성(Sparsity)이 높으면 정확도 급감 | 잠재 요인(Latent Factor) 파악으로 희소성 극복 | 데이터 Sparsity 수준 99% 이상 여부 |

> 요약: 대규모 상용 서비스에서는 희소성과 예측 속도 한계 때문에 메모리 기반 대신 모델 기반(SVD/딥러닝) 추천을 쓴다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Cold Start | 신규 사용자/아이템에 대한 이력 부족 | 초기 가입 시 선호 장르 선택(CBF 하이브리드 결합) | 신규 가입자 추천 클릭률 |
| Sparsity (희소성) | 사용자 수 대비 아이템이 너무 많아 행렬이 빔 | 행렬 분해(Matrix Factorization), 차원 축소 | RMSE, 평점 예측 오차율 |
| Filter Bubble | 과거 취향에만 갇혀 추천 다양성 훼손 | 탐색(Exploration) 알고리즘 도입, 무작위성 부여 | 추천 아이템의 다양성(Diversity) 지표 |

> 요약: 추천의 3대 리스크인 Cold Start, Sparsity, Filter Bubble은 하이브리드 방식과 딥러닝 융합으로 방어한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 오프라인 정확도 | RMSE 감소율, Precision@K 0.8 이상 | 과거 로그 데이터 분할 검증(Train/Test) |
| 온라인 지표 | CTR(클릭률) 5%p 상승, CVR(전환율) 증가 | 실사용자 대상 A/B 테스트 |
| 응답 속도 | 추천 API p95 응답 지연시간 50ms 이하 | 부하 테스트(JMeter) 모니터링 |

> 요약: 추천 성능은 모델 자체의 RMSE(오프라인)와 실제 비즈니스 기여도인 CTR(온라인)을 병행 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 아키텍처 설계: 신규 상품이 등록되면 1차로 콘텐츠 기반(CBF) 랭킹을 매기고, 트래픽이 쌓인 후 협업 필터링(SVD) 가중치를 부여하는 하이브리드 배치를 구성한다.
2. 실시간 반응 반영: 사용자의 최근 10분 클릭(암시적 피드백)을 Redis 등 인메모리 DB에 저장하여 세션 기반 추천(Session-based CF)을 실시간으로 서빙한다.
3. 성과 검증 파이프라인: 추천 알고리즘 변경 시 10% 트래픽만 신규 모델로 라우팅하는 A/B 테스트를 2주간 수행하여 통계적으로 유의미한 CTR 상승 시에만 전면 배포한다.

**결론 (2줄):**
- 기술사 판단: 협업 필터링 단독으로는 한계가 명확하므로, 아이템 메타데이터와 사용자 컨텍스트를 융합하는 하이브리드 추천과 딥러닝(NCF) 도입이 필수다.
- 향후 방향: 최근 추천 시스템은 LLM을 활용한 프롬프트 기반 추천(Conversational Recommender)과 실시간 강화학습(RL) 구조로 진화하며 초개인화를 달성하고 있다.
