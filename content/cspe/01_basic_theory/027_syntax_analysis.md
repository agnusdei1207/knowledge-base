## Ⅰ. 개요
- **정의**: 토큰 스트림이 문맥 자유 문법(CFG)에 부합하는지 검증하고 파스 트리를 생성하는 단계
- **배경/필요성**: 토큰 나열만으로는 프로그램 구조를 파악할 수 없으므로, 문법 규칙에 따른 계층적 구조 분석이 필요함
- **비유**: 단어 카드 나열이 문법에 맞는 문장인지 문법책으로 검사하는 작업과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하향식·상향식 파싱 차이 이해 | LL(1) 예측 파싱 vs LR(1) Shift-Reduce 메커니즘 | LL은 좌측 유도, LR은 우측 유도의 역순이라는 점 혼동 주의 |

> 요약: 토큰 스트림의 문법 적합성을 검증하고 파스 트리를 구성하는 단계임

## Ⅱ. 구성요소
```text
  Token Stream
       |
       v
  +-----------+     +-----------+     +-----------+
  | Parser    |---->| Parse     |---->| Syntax    |
  | (LL/LR)   |     | Tree/AST  |     | Error Mgr |
  +-----------+     +-----------+     +-----------+
       |
       v
  Parsing Table
  (FIRST/FOLLOW or ACTION/GOTO)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Parser | 파싱 테이블과 스택을 이용해 토큰을 문법 규칙에 매칭하는 엔진 | 문법책을 보며 문장 구조를 확인하는 교정자 |
| Parsing Table | LL은 FIRST/FOLLOW 집합, LR은 ACTION/GOTO 테이블로 파싱 동작을 결정함 | 상황별 행동 지침이 적힌 매뉴얼 |
| Parse Tree / AST | 문법 유도 과정을 트리 구조로 표현한 결과물 | 문장의 주어·서술어·목적어 관계를 나타낸 나무 그림 |
| Syntax Error Manager | 구문 오류 발견 시 위치·원인 보고 및 복구를 수행하는 모듈 | 문법 오류에 빨간 줄을 긋는 편집기 |

> 요약: 파서가 파싱 테이블 기반으로 토큰을 분석하여 파스 트리를 생성함

## Ⅲ. 절차
```text
  문법정의          파싱테이블생성     토큰스트림파싱     파스트리출력
  (CFG 명세)       (FIRST/FOLLOW    (Shift/Reduce     (AST 구축)
                    or Canonical)    or Predict)
       |              |              |              |
       +---변환------->+---구동------->+---구축------->+
    생성규칙집합     결정적테이블     스택기반분석     구문구조트리
```
- 1단계: 문맥 자유 문법(CFG)으로 언어의 생성 규칙을 정의함
- 2단계: LL 파서는 FIRST/FOLLOW 집합, LR 파서는 Canonical Collection으로 파싱 테이블을 생성함
- 3단계: LL은 예측(Predict) 방식으로 좌측 유도, LR은 Shift-Reduce 방식으로 우측 유도의 역순 수행함
- 4단계: 파싱 결과를 추상 구문 트리(AST)로 구축하여 후속 단계에 전달함

> 요약: CFG 정의 → 파싱 테이블 생성 → 스택 기반 파싱 → AST 출력 순서로 진행함

## Ⅳ. 문제점
- 문법 충돌: LR 파서에서 Shift-Reduce 또는 Reduce-Reduce 충돌 발생 시 파싱 테이블 생성이 실패함
- LL(1) 제약: 좌재귀 문법이나 공통 접두사가 있으면 LL(1) 파싱이 불가하여 문법 변환이 필요함
- 오류 복구 품질: Panic-mode 복구는 다수의 토큰을 건너뛰어 후속 오류 메시지의 정확도를 저하시킴

> 요약: 문법 충돌·LL(1) 제약·오류 복구 품질이 구문 분석의 주요 과제임

## Ⅴ. 개선방안
1. 단기: LALR(1) 또는 GLR 파서를 적용하여 Shift-Reduce/Reduce-Reduce 충돌을 해소함
2. 중기: 좌재귀 제거·좌인수분해를 자동화하는 문법 전처리 도구를 도입하여 LL(1) 제약을 우회함
3. 장기: Burke-Fisher 등 구문 수준 오류 복구 알고리즘을 적용하여 복구 정확도를 향상함

> 요약: GLR 파서·문법 자동 전처리·구문 수준 복구로 구문 분석 한계를 극복함

## Ⅵ. 전망
- 발전 방향: PEG(Parsing Expression Grammar) 기반 파서, Tree-sitter 등 증분 파서가 IDE 환경에서 확산 중임
- 기술사적 판단: 구문 분석은 프로그래밍 언어뿐 아니라 DSL·프로토콜 파서·데이터 변환기 설계의 핵심 기술임
- 기술사 제언: LL과 LR의 파싱 방향·유도 순서 차이를 파싱 테이블 구성 원리와 함께 이해해야 함
