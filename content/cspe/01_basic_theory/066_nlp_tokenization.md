# 📖 【암기용】 개념 완전 이해

> 목적: 자연어 처리의 토크나이징과 형태소 분석을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 문장을 모델이 처리할 최소 단위로 분해하는 전처리 절차
- **왜 필요한가**: 컴퓨터는 문장을 그대로 계산하지 못하므로 단어·서브워드·형태소 단위로 쪼개 ID와 벡터로 바꿔야 한다.
- **핵심 직관**: 문장을 레고 블록처럼 잘게 나누되, 한국어처럼 조사·어미가 붙는 언어는 의미 단위 경계를 더 세밀하게 찾아야 한다.

## 깊이 이해
- **배경·문제의식**: 영어는 공백만으로 단어 경계를 어느 정도 잡지만 한국어는 "먹었다", "먹고", "먹는"처럼 어간과 어미가 결합한다. 단순 공백 분리는 어휘 수를 늘리고 OOV(Out-of-Vocabulary)를 만든다.
- **작동 원리**: 토크나이저는 문장 정규화, 문장 분리, 토큰 분리, 서브워드 병합, ID 매핑 순서로 동작한다. 형태소 분석기는 품사 태깅을 함께 수행해 "학교에서"를 "학교/NNG + 에서/JKB"처럼 분해한다.
- **비유**: 검색엔진 색인 전에 책을 장·절·문장·단어로 나누는 작업과 같다. 너무 크게 나누면 검색이 거칠고, 너무 잘게 나누면 의미 조합 비용이 커진다.
- **구체 예시**: BPE(Byte Pair Encoding)는 빈도 높은 문자쌍을 반복 병합하여 30,000개 내외 vocabulary로 희귀어 문제를 줄인다. WordPiece는 BERT에서 `##ing` 같은 접사를 서브워드로 표현한다.
- **흔한 오해·주의점**: "토큰 수가 적으면 항상 유리하다"는 틀림. 평균 토큰 수가 줄어도 도메인 신조어가 `[UNK]`로 치환되면 F1 0.82->0.74처럼 개체명 인식 정확도가 하락할 수 있다.

## 연결 개념
- 단어 임베딩 — 토큰 ID를 dense vector로 변환하는 다음 단계
- BERT — WordPiece 기반 양방향 문맥 표현 사용
- 정보검색 — 형태소 분석 품질이 색인어 재현율과 정밀도를 좌우

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 토크나이징·형태소 분석은 자연어 문장을 모델 입력 가능한 토큰 ID와 언어학적 단위로 변환하는 NLP 전처리 핵심이다.
> 2. **가치**: OOV 감소, 한국어 조사·어미 분리, 색인 품질 확보를 통해 분류 F1·검색 재현율·LLM 컨텍스트 비용을 통제한다.
> 3. **판단 포인트**: 공백 기반·형태소 기반·BPE/WordPiece는 언어 특성, 도메인 신조어, vocabulary 크기 8K~100K 조건으로 선택한다.

---

## Ⅰ. 개요 및 필요성

토크나이징은 문장을 토큰 단위로 분해하는 절차이다. 한국어 NLP는 교착어 특성으로 조사·어미·복합명사 처리가 필요하며, 단순 공백 분리는 OOV와 품사 오류를 만든다. LLM·검색·분류 시스템은 토큰 단위로 비용과 정확도가 결정되므로 전처리 기준 수립이 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
원문 문장 -> 정규화 -> 문장 분리 -> 토큰/형태소 분리 -> 토큰 ID
                         +-> 품사 태깅
                         +-> 사전/서브워드 병합
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규화 | 대소문자·기호·공백·Unicode 형태 통일 | NFC/NFKC, URL·이모지 정책 |
| 토크나이저 | 공백·규칙·통계 기반 토큰 경계 결정 | BPE, WordPiece, SentencePiece |
| 형태소 분석기 | 어절을 형태소와 품사로 분해 | 한국어 조사·어미·복합명사 처리 |
| 어휘 사전 | 토큰과 정수 ID 매핑 | 8K~100K vocabulary 관리 |

> 요약: NLP 전처리는 원문을 정규화한 뒤 언어 규칙과 통계 병합으로 토큰 ID와 품사 정보를 산출한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 문장 -> 문자 정규화 -> 후보 경계 탐색 -> 사전/통계 병합
-> 토큰 ID 매핑 -> 모델 입력/색인 생성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원문 수집·정규화 | Unicode 오류율 0.1% 이하 |
| 2 | 토큰 후보 생성 | 평균 토큰/문장, OOV 비율 |
| 3 | 형태소·품사 태깅 | 품사 정확도, NER F1 |
| 4 | ID 매핑·패딩·마스킹 | vocabulary hit rate 99% 이상 |

> 요약: 문장 정규화에서 시작해 토큰 경계 결정, 품사 태깅, ID 매핑 순서로 모델 입력을 만든다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 희귀어를 서브워드로 분해해 `[UNK]` 빈도 축소 | OOV 5%->0.5% 목표 |
| 한계 | 과분절 시 의미 단위가 깨져 문맥 학습 비용 증가 | 평균 토큰 길이, NER F1 동시 확인 |
| 비교 대상 | 공백 토큰화는 영어 뉴스, 형태소 분석은 한국어 검색에 적합 | 언어·도메인·사전 유지비 기준 |

> 요약: 토큰화 방식은 언어 구조와 도메인 어휘 변화율에 따라 정확도와 비용의 균형점이 달라진다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 공백 분리 | 형태소·서브워드 결합 | 한국어 조사·어미 비율 높을 때 |
| 비용/성능 | 사전 구축 비용 낮음, OOV 높음 | vocabulary 32K 기준 OOV 1% 이하 목표 | 도메인 신조어 월 1,000건 이상 |
| 운영/위험 | 규칙 변경 영향 작음 | 사전·모델 동시 버전관리 필요 | 검색 색인 재생성 시간 4시간 이내 |

> 요약: 한국어와 신조어 도메인은 형태소 분석과 서브워드 토큰화를 결합하고, 사전 버전관리를 운영 조건으로 둔다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| OOV 증가 | 신제품명·약어 미등록 | 사용자 사전 월 1회 갱신 | OOV 1% 이하 |
| 과분절 | BPE 병합 횟수 부족 | vocabulary 32K/50K A/B 평가 | 평균 토큰/문장 |
| 품사 오류 | 한국어 중의성·띄어쓰기 오류 | 도메인 말뭉치 재학습 | POS accuracy 96% 이상 |

> 요약: 주요 위험은 OOV·과분절·품사 오류이며, 사전 갱신과 vocabulary 실험으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 토큰 품질 | OOV 1% 이하, 평균 토큰/문장 기준선 대비 +10% 이내 | 샘플 말뭉치 분석 |
| 업무 정확도 | 분류 F1 0.85 이상, NER F1 0.80 이상 | 검증 데이터셋 |
| 운영 통제 | tokenizer 버전·사전 변경 이력 100% 기록 | Git·MLflow·색인 로그 |

> 요약: 토큰화 성공 여부는 토큰 통계, 다운스트림 F1, 버전 변경 이력으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 한국어 검색은 형태소 분석기와 사용자 사전을 적용하고, 색인 재구축 전 OOV 1% 이하를 승인 기준으로 둠
2. LLM 입력은 SentencePiece/BPE 32K·50K vocabulary를 비교하고, 4K 컨텍스트 기준 평균 토큰 수를 측정함
3. 전처리 파이프라인에 tokenizer version, dictionary checksum, 샘플 1,000건 회귀 테스트를 CI에 등록함

**결론 (2줄):**
- 기술사 판단: 영어 일반 문서는 BPE, 한국어 검색·법률·의료 문서는 형태소 분석+도메인 사전 조합을 선택함
- 향후 방향: 다국어 LLM은 byte-level BPE와 언어별 형태소 보정 계층을 함께 운영하는 방향으로 발전함
