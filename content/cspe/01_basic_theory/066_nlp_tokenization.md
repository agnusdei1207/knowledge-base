## Ⅰ. 개요
- 정의: 자연어를 컴퓨터가 처리할 수 있는 최소 단위로 분리하고 의미를 분석하는 과정임.
- 배경: 비정형 텍스트 데이터의 구조화 및 전처리를 위해 필수적임.
- 출제 의도:
| 분류 | 상세 |
| --- | --- |
| 핵심요소 | 토큰화, 어간 추출, 형태소 분석, BPE |
| 주요특징 | 언어 의존성(한국어 교착어), OOV 문제 해결 |

## Ⅱ. 구성요소
- ASCII 구조도
 [Sentence] -> [Tokenizer] -> [T1] [T2] [T3] (Tokens)
      |           |
 [Morph Analyzer] -> [Noun] [Verb] [Josa]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 토큰화 | 텍스트를 단어, 문장, 서브워드 단위로 분리 | 문장 분해 |
| 형태소 분석 | 의미의 최소 단위인 형태소로 분류 및 품사 태깅 | 성분 검사 |
| 서브워드 | 자주 쓰이는 문자열 조합으로 분리 (OOV 방지) | 조립식 가구 |
> 요약: 텍스트를 분석 가능한 조각으로 나누고 문법적 의미를 부여함.

## Ⅲ. 절차
- ASCII 흐름도
[텍스트 세정] -> [토큰 분리] -> [품사 태깅] -> [불용어 제거]
- 4단계 설명
1. 클렌징: 특수문자, HTML 태그 등 불필요한 노이즈를 제거함.
2. 분석 수행: Mecab, KoNLPy 등을 사용하여 형태소를 분리함.
3. 정규화: 표제어 추출(Lemmatization)을 통해 원형을 복원함.
4. 벡터화 준비: 정제된 토큰을 정수 인덱스로 매핑함.
> 요약: 노이즈 제거 후 의미 단위로 분리하여 수치 데이터화 준비함.

## Ⅳ. 문제점
- 신조어나 복합 명사에 대한 분석 오류 및 중의성 처리가 어려움.

## Ⅴ. 개선방안
- 단기: 사용자 정의 사전을 추가하여 도메인 단어를 학습시킴.
- 중기: 서브워드 토큰화(SentencePiece 등)로 미등록어 대응력을 높임.
- 장기: 문맥 기반 언어 모델(Transformer)을 활용해 중의성을 해소함.

## Ⅵ. 전망
- 도메인 특화 용어 처리를 위한 동적 사전 관리 체계가 핵심이며, 향후 LLM의 효율적 토큰 처리를 위한 언어 중립적(Language-agnostic) 서브워드 알고리즘 및 다국어 지원 형태소 분석 엔진의 통합이 가속화될 것임.
- 특히 한국어 특유의 교착어 구조를 반영한 신규 토크나이저 개발이 성능 격차를 만드는 주요 차별화 요소로 작용할 전망임.
