# 📖 【암기용】 개념 완전 이해

> 목적: 토크나이징과 형태소 분석을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 컴퓨터가 자연어를 처리할 수 있도록, 문장을 의미를 가진 최소 단위(토큰)로 쪼개는 과정이다.
- **왜 필요한가**: 컴퓨터는 "나는 밥을 먹었다"라는 통 문장을 이해하지 못한다. 이를 쪼개서 사전(Vocabulary)과 대조해야 각 단어를 숫자로 바꿀 수 있다.
- **핵심 직관**: 한국어는 띄어쓰기만으로 쪼개면 조사("밥을", "밥이") 때문에 사전에 수많은 중복 단어가 생기므로, "밥"과 "을"을 분리하는 형태소 분석이 필수다.

## 깊이 이해
- **배경·문제의식**:
  - 영어는 띄어쓰기(공백) 단위로 단어가 구분되지만, 한국어는 교착어(어근에 조사가 붙는 언어)라서 공백으로 자르면 단어 사전이 기하급수적으로 커진다.
  - OOV(Out of Vocabulary, 미등록 단어) 문제가 발생하면 모델이 단어를 'Unknown'으로 처리하여 성능이 급락한다.
- **작동 원리**:
  - **단어 기반**: 공백 기준으로 분리. 단순하지만 한국어에 부적합.
  - **형태소 기반**: 언어학적 지식(사전)을 바탕으로 어근과 조사를 분리(예: MeCab, KoNLPy). 정확하지만 속도가 느리고 신조어에 약하다.
  - **Subword (BPE 등)**: 통계적으로 자주 같이 등장하는 글자 쌍을 병합해 토큰을 만든다(예: WordPiece). 언어학적 지식 없이도 OOV를 방어한다.
- **비유**: 레고 블록 조립과 같다. 형태소 분석은 완성된 모형(문장)을 정해진 부품(어근, 조사) 단위로 분해하는 것이고, Subword는 자주 붙어있는 부품끼리 묶어서 새로운 모듈로 취급하는 것이다.
- **구체 예시**: "신조어입니다" -> 띄어쓰기: `["신조어입니다"]`, 형태소: `["신조어", "이", "ㅂ니다"]`, Subword: `["신", "##조어", "##입니다"]`
- **흔한 오해·주의점**: 무조건 형태소 분석기가 좋은 것은 아니다. 최근 LLM(GPT, BERT)은 속도와 다국어 처리를 위해 형태소 분석 대신 데이터 기반의 Subword 분할(BPE)을 주로 사용한다.

## 연결 개념
- 서브워드 토큰화 (BPE) — OOV를 방어하는 최신 분할 기법
- 단어 임베딩 (Word2Vec) — 분리된 토큰을 벡터로 변환하는 단계
- 정규화(Normalization) — 대소문자 통일, 특수문자 제거 등 토큰화 이전 단계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 토크나이징과 형태소 분석은 비정형 자연어 텍스트를 기계가 연산할 수 있는 최소 의미 단위(Token)로 분할하는 전처리 과정이다.
> 2. **가치**: 단어 사전(Vocabulary)의 크기를 최적화하고 OOV(미등록 단어) 발생을 억제하여 NLP 모델의 학습 효율과 정확도를 결정한다.
> 3. **판단 포인트**: 정통 NLP 분석에는 언어학 기반 형태소 분석기를 사용하고, 대규모 언어 모델(LLM)에는 통계 기반의 Subword 분할(BPE, WordPiece)을 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 한국어 토크나이징의 난제와 형태소 분석의 필요성 | 교착어 특성과 조사 분리, OOV 문제 지적 | 단순히 "띄어쓰기 분할"로 서술하면 안 됨 |
| 전통적 형태소 분석과 최신 Subword 기법 비교 | BPE(Byte Pair Encoding) 알고리즘과 빈도수 기반 병합 | 언어학적 접근과 통계적 접근의 차이 명시 |

> 요약: 한국어 특성에 따른 형태소 분석의 당위성을 설명하고, 현대 LLM이 채택한 Subword 토크나이징과의 비교를 반드시 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 자연어 코퍼스를 분석 목적에 맞는 의미 있는 최소 단위(Token)로 나누고 정제하는 기법
- 배경: 한국어는 띄어쓰기 기준으로 어절을 나누면 조사/어미가 붙어 어휘 사전 크기가 무한대(Sparsity)로 발산함
- 필요성: 미등록 단어(OOV)를 줄이고 벡터화(Embedding) 단계에서 모델의 계산 복잡도를 $O(V)$ 로 통제하기 위해 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
원시 텍스트 -> 정제(정규화) -> 토크나이저 -> 분할된 토큰 집합 -> 인코딩(정수 맵핑) -> 모델 입력
                              +-> 형태소 사전 / 통계 모델 (BPE)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 정규화(Normalization) | 노이즈 제거, 대소문자 통합, 특수문자 정제 | 정규표현식 활용 |
| 사전(Dictionary) | 기준이 되는 형태소/단어 집합 | 사용자 정의 사전 추가 가능 |
| 분석 엔진 | 규칙 또는 통계 기반으로 토큰 분리 | KoNLPy, SentencePiece |
| 인코더(Encoder) | 분할된 텍스트 토큰을 고유 ID(정수)로 변환 | Vocabulary Table 참조 |

> 요약: 토크나이징 파이프라인은 텍스트 정제, 형태소나 Subword 기반 분할, 그리고 정수 맵핑으로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
텍스트 인입 -> 공백 단위 1차 분할 -> 형태소 분석기 / BPE 적용 -> 최적 토큰 시퀀스 도출 -> ID 변환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 코퍼스 정제 및 전처리 | 불용어(Stopword) 처리율 |
| 2 | 토큰 분할 알고리즘 가동 | 형태소 결합 규칙 또는 빈도수 병합 |
| 3 | 품사 태깅 (POS Tagging) | 명사, 동사 등 품사 식별 (형태소 분석 시) |
| 4 | Vocabulary 구축 및 맵핑 | OOV 토큰(<UNK>) 발생률 1% 이하 |

> 요약: 형태소 분석은 품사 태깅과 사전을 참조하여 분리하고, Subword는 빈도 기반으로 분할하여 OOV를 최소화한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 언어학적 접근 | 사전 기반 형태소 분리 (MeCab, Okt 등) | 정확도 높으나 신조어에 취약하고 속도 느림 |
| 통계적 접근 | Subword 기반 (BPE, WordPiece, SentencePiece) | 신조어 방어 탁월, 다국어 처리 용이 |
| 비교 대상 | 영어 기반 Tokenization | 한국어의 교착어 특성 반영 여부 |

> 요약: 언어학 기반은 정밀한 품사 식별에 유리하고, 통계 기반은 대규모 코퍼스 처리와 OOV 방어에 유리하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | BPE (Byte Pair Encoding) | SentencePiece (Unigram LM) | 선택 기준 |
|:---|:---|:---|:---|
| 분할 알고리즘 | 빈도수 높은 인접 글자쌍을 반복 병합(Greedy) | 유니그램 언어모델 기반 확률 최적 분할 탐색 | 어휘 품질 대비 학습 비용 |
| 사전 토큰화 의존성 | 공백 기준 사전 분리 후 병합, 언어별 전처리 필요 | 원문을 공백 포함 그대로 처리, 언어 독립적 | 다국어·비공백 언어(한국어·중국어) 지원 여부 |
| 대표 적용 모델 | GPT 계열(byte-level BPE), RoBERTa | BERT 계열 WordPiece 변형, T5, ALBERT | 모델 아키텍처의 토크나이저 표준 호환성 |

> 요약: BPE는 빈도 기반 탐욕적 병합으로 구현이 단순하고, SentencePiece는 확률 모델과 공백 처리 내장으로 다국어 파이프라인에 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 사전 미등록(OOV) | 도메인 특화 용어, 신조어 유입 | 사용자 정의 사전(Custom Dict) 주기적 업데이트 | <UNK> 토큰 비율 |
| 분할 모호성 | 문맥에 따라 다르게 나뉘는 형태소 | 형태소 분석 전후 띄어쓰기 교정(PyKoSpacing) | 토큰 정확도 |
| 속도 저하 | 대용량 코퍼스를 무거운 분석기로 처리 | C++ 기반 MeCab 사용 또는 SentencePiece 전환 | 초당 토큰 처리량 (TPS) |

> 요약: OOV와 속도 저하 리스크는 도메인 사전 추가와 경량화된 Subword 알고리즘 전환으로 방어한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| OOV 비율 | 전체 말뭉치 기준 1% 이하 | 토큰 빈도 분포 모니터링 |
| 처리 성능 | 1GB 텍스트 기준 1분 이내 처리 | Batch 파이프라인 지연시간 |
| 다운스트림 성능 | 의도 분류, 감성 분석 등 F1-score 향상 | 최종 태스크 벤치마크 평가 |

> 요약: 토크나이징의 품질은 단독으로 평가하기보다 OOV 비율 감소와 최종 응용 모델의 성능 향상폭으로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 챗봇/분류 모델: 고객 VOC 분석 시, 제품명과 은어가 많은 특성을 반영하여 MeCab에 사용자 정의 사전을 주 1회 동기화하여 적용한다.
2. 거대 모델 사전학습: 한국어 특화 LLM 구축 시, 형태소 분석기의 속도 병목을 피하기 위해 원시 텍스트를 BPE 기반 SentencePiece로 훈련해 단어 사전을 구축한다.
3. 데이터 정제: 토큰화 이전 단계에서 정규표현식과 띄어쓰기 교정 모듈을 배치하여 띄어쓰기 오류로 인한 형태소 오분할 확률을 50% 이상 낮춘다.

**결론 (2줄):**
- 기술사 판단: 정교한 의미 분석과 명사 추출이 필요한 업무는 형태소 분석기를, 대규모 딥러닝과 다국어 확장이 필요한 경우 Subword 토큰화를 선택해야 한다.
- 향후 방향: 최근 LLM 트렌드는 복잡한 언어학적 전처리 없이, 데이터에 내재된 통계적 패턴(BPE)만으로 문맥을 파악하는 End-to-End 방식으로 통합되고 있다.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "설명하시오", "기술하시오" | 형태소 분석과 토크나이징 절차 | 교착어의 특성과 OOV 한계 |
| 요구사항 명시형 | "BPE와 비교하시오", "해결 방안을 제시하시오" | 전통적 분석 vs 통계적 분할(BPE) 구조 차이 | OOV 문제 극복을 위한 Subword 전환 기준 |

> 요약: 설명형은 한국어 처리의 일반적 절차를, 비교/방안형은 OOV 한계 극복을 위한 BPE 도입과 사전 관리 체계를 중심으로 전개한다.
