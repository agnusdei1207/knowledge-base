## 미리 알고가기

- 코퍼스: 토크나이저 학습과 평가에 쓰는 텍스트 말뭉치임
- 토큰: 모델이 처리하는 최소 입력 단위임
- 형태소: 뜻을 가진 가장 작은 언어 단위임
- 서브워드: 단어를 더 작은 빈도 기반 조각으로 나눈 단위임
- OOV (Out-of-Vocabulary): 학습 사전에 없어 직접 표현하기 어려운 미등록 단어임
- 어휘 사전: 토큰 문자열과 정수 ID를 연결한 목록임

## Ⅰ. 개요

- **정의/개념**: 토크나이징은 원문 텍스트를 모델 입력 단위인 토큰으로 나누고, 형태소 분석은 단어를 의미 단위와 품사로 분해하는 자연어 전처리 과정임
- **배경/필요성**: 불규칙한 띄어쓰기와 다양한 어미·신조어를 모델에 입력하기 위해 일관된 분절 기준이 필요함

## Ⅱ. 특징

- 텍스트를 정수 ID 시퀀스로 바꾸는 첫 단계임
- 한국어는 조사와 어미 때문에 형태소 분석 품질이 토큰 의미를 좌우함
- 서브워드는 OOV를 줄이고 어휘 사전 크기를 조절함
- 토큰 수는 모델 메모리, 비용, 문맥 길이에 직접 영향을 줌

## Ⅲ. 종류 및 비교

| 판단 기준 | 형태소 분석 | 서브워드 분절 | 문자 분절 |
|:---|:---|:---|:---|
| 분할 기준 | 문법 사전·품사 | 말뭉치 빈도 | 문자 단위 |
| 장점 | 의미와 품사 보존 | OOV와 사전 크기 균형 | 미등록어가 거의 없음 |
| 한계 | 신조어·고유명사 취약 | 의미 경계가 깨짐 | 시퀀스가 길어짐 |
| 대표 적용 | 검색, 전통 NLP | BERT, GPT 계열 입력 | 초경량·다국어 처리 |
| 관리 포인트 | 사용자 사전 | 어휘 크기 | 길이 증가 비용 |

> 요약: 형태소 분석은 의미 보존, 서브워드는 사전 효율, 문자 분절은 OOV 제거에 초점이 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정규화 | 유니코드, 대소문자, 공백 표현을 통일함 |
| 분절 알고리즘 | 형태소, BPE, WordPiece 등 경계를 정함 |
| 어휘 사전 | 토큰을 고유 정수 ID로 매핑함 |
| 특수 토큰 | 문장 시작, 분리, 패딩, 미등록어를 표시함 |
| 디코더 | 토큰 ID를 다시 문자열로 복원함 |

> 요약: 토크나이저는 정규화, 분절, 사전 매핑, 복원 기능으로 입력을 통제함.

```text
원문 텍스트
  -> 정규화
  -> 토큰 분절
  -> 토큰 ID 매핑
  -> 임베딩 계층 입력
```

## Ⅴ. 원리 및 절차 흐름도

```text
코퍼스 -> 정규화 -> 어휘 사전 학습 -> 텍스트 토큰화 -> ID 인코딩
```

1. 코퍼스의 문자 형식과 공백을 정규화함
2. 언어 특성과 모델 목적에 맞는 분절 방식을 선택함
3. 학습 말뭉치에서 어휘 사전을 만들거나 기존 사전을 적용함
4. 입력 문장을 토큰 ID로 변환해 임베딩 계층에 전달함

> 요약: 토크나이징 품질은 정규화와 분절 기준, 어휘 사전이 모델 입력 비용과 의미 보존을 함께 결정함.

## Ⅵ. 실무 사례

1. 한국어 서비스에서 범용 다국어 토크나이저를 그대로 쓰면 토큰 수가 늘어나므로 한국어 코퍼스 기반 사전을 비교하고 평균 토큰 길이와 성능을 함께 확인함
2. 형태소 분석은 신조어와 브랜드명을 놓치기 쉬우므로 사용자 사전을 운영하고 검색 누락률이나 개체명 인식 성능으로 검증함

## Ⅶ. 결론

- 토크나이징은 자연어 모델의 입력 품질을 결정하는 전처리이며, 언어 구조와 비용 제약에 맞는 분절 기준을 선택해야 함

## 작성 근거(검토용)

- 개요는 토크나이징과 형태소 분석을 구분해 키워드의 복합 성격을 명확히 함
- 특징은 한국어 처리, OOV, 토큰 수 비용처럼 모델 성능에 직접 영향을 주는 요소만 남김
- Ⅲ은 형태소·서브워드·문자 분절을 비교해 언어와 모델별 선택 기준을 제시함
- Ⅳ는 정규화부터 ID 매핑까지 입력 파이프라인의 구성요소를 순서 있게 배치함
- Ⅵ은 한국어 토큰 효율과 사용자 사전 운영을 실무 리스크로 선정함
