## 미리 알고가기

- 토큰: 모델이 입력 단위로 처리하는 단어, 형태소, 서브워드, 문자 조각임
- 어휘 사전: 토큰과 정수 ID를 매핑한 고정 또는 학습된 목록임
- OOV: 학습 사전에 없는 단어가 입력되어 의미 표현이 어려운 상태임
- 서브워드: 단어보다 작고 문자보다 큰 단위로 신조어와 복합어를 처리하는 분절 단위임
- BPE: 자주 붙어 나오는 문자 조각을 반복 병합해 어휘를 만드는 방식임
- SentencePiece: 공백에 의존하지 않고 원문 문자열에서 직접 서브워드를 학습하는 방식임

## Ⅰ. 개요

- **정의**: 토크나이징은 자연어 문장을 모델 입력 단위인 토큰 시퀀스와 정수 ID로 변환하는 전처리 절차임
- **배경/필요성**: 텍스트는 사람이 읽는 문자열이지만 모델은 고정된 ID 시퀀스를 입력으로 받으므로 일관된 분절 기준이 없으면 학습과 추론 결과가 달라짐
- **비유**: 긴 문장을 레고 블록처럼 일정한 규격의 조각으로 잘라 모델이 조립할 수 있게 만드는 과정과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 토크나이징 역할 설명 | 문자열을 토큰 ID와 attention mask로 변환 | 단순 띄어쓰기 분리로만 설명 |
| 서브워드 방식 비교 | BPE, WordPiece, SentencePiece | OOV와 시퀀스 길이 트레이드오프 누락 |

> 요약: 토크나이징은 텍스트를 어떤 기준으로 잘라 어떤 ID로 표현할지 정하는 NLP 입력 품질의 첫 단계임

## Ⅱ. 특징/비교

| 판단 기준 | 단어/형태소 토큰화 | 서브워드 토큰화 | 바이트/문자 토큰화 |
|:---|:---|:---|:---|
| 분절 기준 | 공백, 형태소 분석, 사전 규칙 | 통계적 병합 또는 확률 기반 조각 | 문자 또는 바이트 단위 |
| OOV 대응 | 사전 밖 단어에 취약함 | 미등록어를 조각으로 분해해 대응함 | 원칙적으로 OOV가 거의 없음 |
| 시퀀스 길이 | 짧지만 사전 크기가 커질 수 있음 | 길이와 사전 크기를 중간 수준에서 절충함 | 길이가 길어져 계산 비용이 증가함 |
| 선택 조건 | 형태소 정보가 중요한 언어 분석 | 범용 LLM과 다국어 모델 | 극단적 신조어·코드·바이너리 입력 |

> 요약: 토큰화 방식은 OOV 감소, 시퀀스 길이, 언어별 경계 모호성을 함께 고려해 선택해야 함

- **한국어 고려**: 조사와 어미 결합이 많아 공백 기준만으로는 의미 단위를 일관되게 분리하기 어려움
- **모델 고려**: BERT 계열은 WordPiece, GPT 계열은 BPE 계열처럼 모델 사전과 토크나이저가 결합됨
- **운영 고려**: 토크나이저를 바꾸면 입력 ID 체계가 바뀌므로 기존 임베딩과 모델을 그대로 재사용하기 어려움

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Raw Text    | ---> | Normalizer  | ---> | Tokenizer   |
| sentence    |      | unicode     |      | split rule  |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Vocab       | <--- | Token IDs   | ---> | Attention   |
| Dictionary  |      | sequence    |      | Mask        |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정규화기 | 대소문자, 유니코드, 공백, 특수문자를 일관된 형태로 보정함 | 재료 세척 |
| 분절 알고리즘 | BPE, WordPiece, SentencePiece 등으로 토큰 경계를 결정함 | 절단기 |
| 어휘 사전 | 토큰 문자열과 정수 ID를 매핑해 모델 입력 공간을 고정함 | 단어장 |
| 특수 토큰 | `[CLS]`, `[SEP]`, `[PAD]`, `[UNK]` 등 태스크 제어용 토큰임 | 표지판 |
| attention mask | padding과 실제 토큰을 구분해 모델이 참고할 위치를 지정함 | 읽기 표시 |

> 요약: 토크나이징은 정규화, 분절, 사전 매핑, 특수 토큰, 마스크를 결합해 문자열을 모델 입력으로 바꿈

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Normalize | --> | Split     | --> | Map IDs   | --> | Pad / Mask|
| Text      |     | Subword   |     | by Vocab  |     | Sequence  |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
clean string       tokens            integer ids        fixed batch
```

1. **텍스트 정규화**: 유니코드 형식, 공백, 대소문자, 특수문자 처리 기준을 모델 학습 기준과 맞춤
2. **토큰 분절**: 단어, 형태소, 서브워드, 바이트 중 선택한 알고리즘으로 문자열을 토큰으로 나눔
3. **ID 변환**: 어휘 사전을 참조해 각 토큰을 정수 ID로 바꾸고 미등록 토큰은 분해 또는 `[UNK]`로 처리함
4. **길이 정렬**: padding, truncation, attention mask를 적용해 배치 입력 길이를 맞춤

> 요약: 토크나이징 절차는 문자열 표기를 통일하고 분절한 뒤 ID와 마스크로 바꾸어 모델이 읽는 입력 형식을 만드는 과정임

## Ⅴ. 문제점

- **P1 OOV와 의미 손실**: 도메인 신조어, 약어, 고유명이 `[UNK]` 또는 과도한 조각으로 변환되면 의미 정보가 줄어듦
- **P2 언어별 분절 오류**: 한국어처럼 조사·어미 결합이 복잡한 언어는 형태소 경계가 흔들려 같은 단어가 문맥마다 다른 토큰열로 분리됨
- **P3 사전 크기와 길이 트레이드오프**: 사전이 작으면 시퀀스가 길어지고, 사전이 크면 희소 토큰과 메모리 비용이 증가함

> 요약: 토크나이저 품질은 미등록어 처리, 언어 구조 반영, 사전 크기 선택에서 주로 실패함

## Ⅵ. 개선방안

- **P1 대응**: 도메인 코퍼스로 BPE/SentencePiece를 재학습하고 사용자 사전을 보강함 (확인: OOV율, 평균 토큰 수)
- **P2 대응**: 형태소 분석기와 서브워드 토크나이저를 결합하거나 한국어 전용 사전을 적용함 (확인: 형태소 F1, downstream 성능)
- **P3 대응**: vocab size 후보별 평균 시퀀스 길이와 검증 성능을 비교해 운영 비용 기준으로 선택함 (확인: p95 입력 길이, GPU 메모리)

> 요약: 도메인 사전, 언어별 분절 보정, 사전 크기 실험으로 토크나이징의 입력 품질과 비용을 균형화함

## Ⅶ. 전망

- **발전 방향**: LLM과 멀티모달 모델에서는 텍스트뿐 아니라 코드, 이미지 패치, 음성 단위를 함께 다루는 토큰화가 확대될 전망임
- **기술사적 판단**: 모델 아키텍처가 같아도 토크나이저가 다르면 성능과 비용이 달라지므로 입력 계층의 설계 자산으로 관리해야 함
- **기술사 제언**: 답안에서는 토큰화가 단순 전처리가 아니라 OOV, 길이, 사전, 모델 호환성을 결정하는 구조라고 설명해야 함
