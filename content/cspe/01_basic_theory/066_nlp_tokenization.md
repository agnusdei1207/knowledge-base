# 066. 자연어 처리 — 토크나이징·형태소 분석 (NLP Tokenization)

## Ⅰ. 개요

- **정의/개념**: 비정형 텍스트 데이터를 모델이 처리할 수 있는 의미 있는 최소 단위인 토큰(Token)으로 분리하고, 이를 숫자(Index)로 변환하는 자연어 처리(NLP)의 가장 기초적인 전처리 과정임
- **배경/필요성**: 컴퓨터는 텍스트를 직접 이해하지 못하므로 수치화된 벡터로 변환해야 하며, 특히 한국어와 같은 교착어는 단순 공백 분리가 어렵기 때문에 언어적 특성을 고려한 정교한 분절 기술이 필수적임

## Ⅱ. 특징 및 비교

| 판단 기준 | 단어 단위 (Word) | 형태소 단위 (Morphology) | 서브워드 단위 (Subword) |
|:---|:---|:---|:---|
| **분리 기준** | 공백(띄어쓰기) 중심 | 의미/문법적 최소 단위 | 빈도 기반 부분 단어 분할 |
| **장점** | 구현이 매우 단순함 | 한국어 문법 특성 반영 탁월 | OOV 문제 해결, 범용성 높음 |
| **단점** | 사전에 없는 단어(OOV) 취약 | 분석기 성능에 의존적 | 토큰 시퀀스 길이가 길어짐 |
| **대표 기법** | White-space Tokenizer | KoNLPy (Mecab, Okt 등) | BPE, WordPiece, SentencePiece |

> 요약: 과거에는 형태소 분석이 주류였으나, 최근 LLM 시대에는 언어에 무관하게 OOV 문제를 해결하는 서브워드 방식이 표준으로 자리 잡음

## Ⅲ. 구성요소/구조

- **구성요소**:
  - **Normalization**: 대소문자 통일, 특수문자 제거, 유니코드 정규화(NFC/NFD) 등 텍스트를 일정한 형식으로 맞춤
  - **Stopwords (불용어)**: 분석에 기여도가 낮은 조사, 접속사 등을 제거하여 노이즈를 줄임
  - **Vocabulary (어휘 사전)**: 토큰과 고유 인덱스를 매핑한 표로, 모델 학습의 기초가 됨
  - **BPE (Byte Pair Encoding)**: 가장 빈번하게 등장하는 문자 쌍을 반복적으로 병합하여 서브워드 사전을 구축하는 알고리즘임
  - **OOV (Out-Of-Vocabulary)**: 학습 데이터에 없던 단어가 등장하여 `[UNK]` 토큰으로 처리되는 현상임

- **전처리 프로세스 흐름도**:
```text
[Raw Text] -> [Normalization] -> [Tokenization] -> [Post-processing] -> [Indexing] -> [Model Input]
     |              |                 |                  |                 |              |
 "Hello World"  "hello world"    ["hello", "world"]  (Stopwords 제거)  [104, 321]      Tensor
```

## Ⅳ. 문제점 및 개선방안

1. **[미등록어(OOV) 발생]**: 신조어나 전문 용어가 `[UNK]` 토큰으로 바뀌면서 문맥 정보가 손실됨
   - **개선방안**: 글자 단위로 쪼개거나 BPE 기반의 서브워드 토크나이저를 사용하여 미등록어를 하위 단위로 분해함 (확인: UNK 토큰 비율)
2. **[한국어 띄어쓰기 오류]**: 인터넷 신조어나 띄어쓰기가 무시된 텍스트는 토큰화 품질을 급격히 떨어뜨림
   - **개선방안**: 띄어쓰기에 강건한 분석기(Soynlp)를 사용하거나 사전 정규화 단계에서 자동 띄어쓰기 보정 모델을 적용함 (확인: 분절 정확도)
3. **[의미 단위의 파편화]**: 서브워드 분할 시 본래의 의미가 지나치게 쪼개져 문맥 파악이 어려워질 수 있음
   - **개선방안**: 모델 학습 시 적절한 Vocabulary 크기를 설정하고, 도메인 특화 데이터로 사전을 재구축함 (확인: 의미 보존율)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **검색 엔진** | 문서 색인 시 형태소 분석기를 사용하여 의미 기반 키워드 추출 | Precision, Recall (재현율) |
| **챗봇 (LLM)** | SentencePiece를 사용하여 다국어 및 신조어에 대응하는 입력 토큰 생성 | 생성 텍스트의 자연스러움, OOV율 |
| **감성 분석** | 불용어를 제거하고 감정 형용사 중심의 토큰화 수행 | 분류 정확도 (Accuracy) |

> 요약: 실무에서는 도메인 데이터의 특성(구어체, 문어체 등)에 따라 적절한 토크나이저를 선택하고 튜닝하는 과정이 필수적임

## Ⅵ. 결론

토크나이징은 "Garbage In, Garbage Out" 원칙이 가장 극명하게 드러나는 단계로, 모델의 성능 상한선을 결정짓는 핵심 전처리 기술임. 최근에는 고정된 규칙 기반의 분석을 넘어 데이터 기반의 확률적 토크나이징으로 발전하고 있으며, 특히 다국어 모델이 보편화되면서 언어 장벽을 허무는 바이트 수준(Byte-level)의 효율적인 분절 전략이 더욱 중요해지고 있음.
