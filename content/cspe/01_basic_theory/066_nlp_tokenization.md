## 미리 알고가기

- 코퍼스($Corpus$): 자연어 연구를 위해 텍스트 데이터를 모아놓은 거대한 말뭉치임
- 토크나이저($Tokenizer$): 원문 텍스트를 기계가 처리할 수 있는 가장 작은 단위인 토큰($Token$)으로 분할하는 변환 모듈임
- 서브워드($Subword$): 자주 쓰이는 어근이나 접사 등을 기준으로 단어를 더 작은 단위로 쪼개어 어휘 사전을 구성하는 방식임
- 미등록 단어($OOV$): 모델 학습 시 구축한 어휘 사전($Vocabulary$)에 없어 분석할 수 없는 새로운 단어임

## Ⅰ. 개요

- **정의/개념**: 토크나이징은 원시 텍스트를 컴퓨터가 이해할 수 있는 최소 의미 단위인 토큰으로 분할하는 과정이며, 형태소 분석은 단어에서 뜻을 가진 가장 작은 언어적 단위를 추출하고 품사를 결합하는 교착어 전용 분석 기법임
- **배경/필요성**: 컴퓨터는 텍스트를 가공되지 않은 상태로 읽으면 복합어나 어미 변화를 개별적인 무작위 단어로 인식하므로, 단어의 본질적인 형태적 규칙과 통계적 특징을 주입하기 위한 전처리가 필수적임

## Ⅱ. 특징

- 영어와 같은 굴절어는 단순 공백($Whitespace$) 기준으로 분할해도 문맥이 크게 훼손되지 않으나, 조사와 어미가 발달한 한국어(교착어)는 형태소 분석이나 전용 서브워드 분절이 필요함
- 서브워드 분절 기법(예: $BPE, WordPiece$)은 단어 사전에 없는 새로운 어휘가 등장하더라도 이를 이미 아는 부분 문자열의 결합으로 분리하여 학습을 지속할 수 있게 함
- 토크나이징 품질에 따라 인코더가 학습해야 할 최종 사전($Vocabulary$)의 크기가 결정되며, 이는 가중치 임베딩 행렬의 메모리 크기와 직접적으로 직결됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 형태소 분석 (Morpheme) | 서브워드 분절 (Subword/BPE) | 캐릭터 분절 (Character) |
|:---|:---|:---|:---|
| **분할 방식** | 문법적 규칙 및 품사 사전 기반 | 통계적 빈도(바이트 페어) 기반 | 문자 글자 한 개 단위 분절 |
| **OOV 대응** | 미등록 단어 시 형태 분석 실패 | 신조어도 자소/서브 단어로 복원 가능 | 미등록어 없음 (모든 자모 수용) |
| **의미 보존** | 매우 높음 (품사 수준 식별) | 높음 (빈번한 어근 결합) | 낮음 (자소 분해 시 의미 유실) |
| **어휘 사전크기** | 중간 | 사용자가 임의 크기 설정 가능 | 매우 작음 (알파벳/자모 개수) |
| **대표 적용** | 전통 한글 검색엔진, 통계 기법 | 트랜스포머 기반 언어 모델 ($LLM$) | 다국어 경량 텍스트 처리 |

> 요약: 형태소 분석은 '문법적 뜻'에 집중하고, 서브워드는 '빈도수와 사전 효율성'에 집중함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 텍스트 정규화 | 특수 문자 제거, 유니코드 표준화(NFC/NFD) 등을 통해 입력의 형식을 맞추는 작업임 |
| 바이트 페어 인코딩 | 가장 빈번하게 등장하는 바이트 쌍을 하나의 토큰으로 병합해 나가는 통계 알고리즘임 |
| 품사 판정기 | 형태소 분석에서 나뉜 각 토큰에 $NNG$(일반명사), $JKS$(주격조사) 등의 품사 태그를 할당함 |
| 스페셜 토큰 | 문장의 시작($[CLS]$), 끝($[SEP]$), 미등록어($[UNK]$) 등을 가리키는 시스템 토큰임 |

```text
[ 한국어 텍스트 분절 비교 ]
"자연어처리는 재밌다"
- 공백 분절: ['자연어처리는', '재밌다'] -> OOV 취약
- 형태소 분절: ['자연어', '처리', '는', '재밌', '다'] -> 형태소/품사 분석
- 서브워드(BPE): ['자연어', '##처리', '##는', '재', '##밌다'] -> 빈도 기반
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 원시 텍스트  | --> | 정규화/정제  | --> | 토큰 경계분할| --> | 정수 인덱싱  |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **원문 정제** — 텍스트 내 스팸성 태그나 특수 기호를 필터링하고 대소문자를 일치시키는 정규화 작업을 진행함
2. **사전 매핑/학습** — 수집된 말뭉치 전체에서 자주 등장하는 문자열 조합을 추출하여 일정 크기(예: 32,000개)의 어휘 사전을 학습시킴
3. **분절 연산** — 학습된 토크나이저 사전의 어휘 순서대로 최장 일치 규칙에 따라 원문을 가장 효율적인 서브워드 배열로 분할함
4. **인코딩 수행** — 분할된 각 토큰 문자열을 사전 상의 고유한 정수 인덱스($ID$)로 변환하여 신경망의 임베딩 레이어로 주입함

## Ⅵ. 실무 적용 및 유의점

1. 한국어 데이터로 대규모 언어 모델을 학습할 때, 다국어 사전을 그대로 사용하면 한글 단어가 자소 단위로 비효율적으로 쪼개져 토큰 소모량이 폭증하므로, 반드시 한국어 코퍼스로 사전 학습된 'Ko-Tokenizer'를 별도 구축해 활용해야 함
2. 형태소 분석기 활용 시 '신조어'나 '브랜드명'은 명사로 올바르게 분리되지 못하는 경우가 많으므로, 분석기의 사용자 사전에 특수 고유명사를 상시 등록하여 엔티티($Entity$) 유실을 막아야 함

## Ⅶ. 결론

- 토크나이징은 인공지능이 자연어의 질서를 마주하는 첫 관문이며, 설계자는 학습할 데이터 언어의 통계적 특성과 어휘 사전의 용량 효율성을 입체적으로 조율하여 언어 모델의 근본 체력을 설계해야 함
