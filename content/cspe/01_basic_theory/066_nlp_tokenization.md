# 066. 자연어 처리 — 토크나이징·형태소 분석 (NLP Tokenization)

## Ⅰ. 개요

- **정의/개념**: 비정형 텍스트 데이터를 모델이 처리할 수 있는 의미 있는 최소 단위인 토큰(Token)으로 분리하고, 이를 수치화된 인덱스($Index$)로 매핑하는 자연어 처리($NLP$)의 핵심 전처리 공정임
- **배경/필요성**: 컴퓨터의 수치 연산 구조상 텍스트 직접 처리가 불가능하므로 $Vector$ 변환이 필수적이며, 특히 한국어와 같은 교착어는 어근과 조사가 결합된 특성으로 인해 단순 공백 분리를 넘어선 정교한 형태소 분석 및 분절 기술이 요구됨

## Ⅱ. 특징 및 비교

### 1. 토큰화 전략별 비교

| 판단 기준 | 단어 단위 (Word) | 형태소 단위 (Morphology) | 서브워드 단위 (Subword) |
|:---|:---|:---|:---|
| **분리 기준** | 공백(White-space) 기반 | 의미/문법적 최소 단위 | 빈도 기반 부분 단어 분할 |
| **$OOV$ 대응** | 취약 (사전 외 단어 처리 불가) | 보통 (미등록어 분석 한계) | 우수 ($Byte$ 단위 분해 가능) |
| **언어 의존성** | 낮음 (영어권 유리) | 높음 (한국어/일본어 특화) | 낮음 (범용적 적용 가능) |
| **대표 기법** | $Split()$ | $KoNLPy$, $Mecab$ | $BPE$, $WordPiece$ |

> 요약: 모델의 범용성과 $OOV(Out-Of-Vocabulary)$ 문제 해결을 위해 최신 $LLM$은 서브워드 기반의 $SentencePiece$ 방식을 표준으로 채택함

### 2. $PPA$ 관점의 트레이드오프 ($Trade-offs$)
- **Performance**: 토큰 단위가 작을수록($Character$-$level$) $OOV$는 줄어드나 시퀀스 길이($L$)가 길어져 연산 복잡도($O(L^2)$)가 급증함
- **Precision**: 형태소 기반은 한국어의 의미적 정확성을 높이나, 분석기 자체의 오류가 모델 전체로 전이될 위험($Cascade$ $Error$)이 존재함
- **Area(Resource)**: 어휘 사전($Vocabulary$) 크기가 클수록 표현력은 좋아지나 임베딩 레이어의 파라미터 수가 증가하여 메모리 점유율이 상승함

## Ⅲ. 구성요소/구조

### 1. 토큰화 아키텍처 인사이트 ($Architecture$ $Insight$)
- **Normalization**: 유니코드 정규화($NFC/NFD$), 대소문자 통일, 노이즈 제거를 통해 입력 데이터의 엔트로피를 감소시킴
- **Pre-tokenization**: 원문 텍스트를 공백이나 구두점 기준으로 1차 분할하여 서브워드 알고리즘의 효율성을 높임
- **Encoder/Decoder**: $BPE$나 $WordPiece$ 알고리즘을 통해 구축된 사전을 기반으로 텍스트를 $ID$로 변환하거나 그 반대의 과정을 수행함

### 2. 처리 절차 및 흐름도
```text
[Raw Corpus] -> [Normalization] -> [Pre-tokenization] -> [Subword Algorithm] -> [Vocabulary]
      |               |                  |                    |                  |
   원문 데이터     노이즈 제거       공백/구두점 분할      빈도 기반 병합/분할    토큰-ID 매핑
```

## Ⅳ. 문제점 및 개선방안

### 1. 실무적 문제점 및 대응 전략
1. **[미등록어($OOV$)에 의한 정보 소실]**: 학습 데이터에 없는 단어가 `[UNK]`로 치환되어 문맥이 파괴됨
   - **개선방안**: $Byte$-level $BPE$를 적용하여 모든 문자를 $ASCII/UTF-8$ 바이트 단위로 분해, 어떤 단어든 생성 가능하게 함 (확인: $UNK$ 발생 빈도)
2. **[한국어 띄어쓰기 부정확성]**: 소셜 미디어나 구어체 데이터에서 띄어쓰기 누락 시 분절 품질이 급격히 저하됨
   - **개선방안**: 띄어쓰기에 강건한 $Soynlp$ 또는 비지도 학습 기반의 토크나이저를 사용하고 전처리 단계에서 자동 교정 모델을 결합함 (확인: $F1$-$Score$)
3. **[의미 단위 파편화와 연산 비용]**: 과도한 서브워드 분할은 모델이 처리해야 할 시퀀스 길이를 늘려 추론 지연($Latency$)을 유발함
   - **개선방안**: 도메인 특화 사전을 구축하여 빈번한 복합 명사는 하나의 토큰으로 유지, $Vocab$ 효율을 최적화함 (확인: $Tokens$ $per$ $Sample$)

### 2. 리얼월드 트러블슈팅 ($Real-world$ $Troubleshooting$)
- **상황**: 법률/의료 도메인 적용 시 전문 용어가 일반 서브워드 사전에 의해 과하게 쪼개져 성능 저하 발생
- **해결**: 해당 도메인 코퍼스를 추가 학습($Domain$ $Adaptation$)하여 사전을 확장하거나, 사용자 정의 사전($User$ $Dictionary$)을 통해 핵심 키워드의 고유 $ID$를 강제 보존함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **검색 엔진 색인** | 형태소 분석기를 통해 조사·어미를 제거하고 실질 형태소(명사) 추출로 검색 정확도 향상 | $mAP$, $Recall$ |
| **초거대 언어모델 ($LLM$)** | $SentencePiece$를 사용하여 언어 제약 없이 대규모 말뭉치를 효율적으로 압축 및 학습 | $Perplexity$, $Compression$ $Ratio$ |
| **기계 번역** | 소스 언어와 타겟 언어의 공통 서브워드 사전을 구축하여 번역의 일관성 유지 | $BLEU$ $Score$ |

## Ⅵ. 결론

토크나이징은 "Garbage In, Garbage Out" 원칙이 적용되는 최전방 공정으로, 단순히 텍스트를 쪼개는 것을 넘어 모델의 정보 처리 밀도를 결정하는 핵심 설계 요소임. 향후 토크나이저가 없는($Tokenizer$-free) 모델에 대한 연구가 지속되고 있으나, 현재로서는 $PPA$ 최적화를 위해 도메인 특화 사전 구축과 확률적 분절 기법($Subword$ $Regularization$)의 조화가 실무적 성공의 관건임.
