## 미리 알고가기

- 토큰: 모델이 처리하는 최소 단위 문자열임
- 형태소: 의미를 가지는 최소 언어 단위임
- OOV: 사전에 없는 미등록 단어 문제임

## Ⅰ. 개요

- **정의/개념**: 토크나이징은 문장을 모델 입력 단위로 분할하는 과정이고, 형태소 분석은 단어를 의미 단위로 나누고 품사를 부여하는 언어 전처리 단계임
- **배경/필요성**: 자연어는 띄어쓰기, 어형 변화, 복합어가 복잡하므로, 그대로는 모델이 의미를 안정적으로 학습하기 어려움

## Ⅱ. 특징

- 전처리 품질이 이후 임베딩과 모델 성능에 직접 영향 줌
- 한국어처럼 교착어는 형태소 분석 중요도가 높음
- subword 토크나이징은 OOV 문제를 크게 완화함
- 토큰 분할 방식이 달라지면 모델 크기와 의미 보존 품질이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 단어 단위 | 형태소 단위 | Subword |
|:---|:---|:---|:---|
| OOV 대응 | 약함 | 중간 | 강함 |
| 의미 보존 | 중간 | 높음 | 중간~높음 |
| 어휘 수 | 큼 | 중간 | 작음 |
| 대표 적용 | 전통 NLP | 한국어 처리 | BERT, GPT |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정규화 | 소문자화, 특수문자 처리 등이며 입력 일관성 확보 단계임 |
| 분절기 | 토큰 또는 형태소 경계를 나눔 전처리 핵심 로직임 |
| 사전/모델 | 분석 기준 지식이며 정확도와 속도를 좌우함 |
| 인덱싱 | 토큰을 정수 ID로 변환하고 모델 입력 형식임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문장입력 | --> | 정규화 | --> | 분절/분석 | --> | ID변환 |
+----------+     +----------+     +----------+     +----------+
```

1. **문장입력**: 원문 텍스트를 수집함
2. **정규화**: 불필요한 표기 차이를 줄임
3. **분절/분석**: 토큰 또는 형태소 단위로 나눔
4. **ID변환**: 사전과 매핑해 모델 입력으로 바꿈

## Ⅵ. 문제점 및 해결 방안

1. **언어별 경계 규칙 차이가 큼**: 한국어, 중국어는 단순 공백 분할이 부적합함
   - **해결 방안**: 언어 특화 tokenizer와 형태소 분석기를 사용하고 token accuracy로 검증함
2. **희귀어와 신조어 처리에 약할 수 있음**: 미등록 단어가 늘어남
   - **해결 방안**: BPE, WordPiece 등 subword를 적용하고 OOV rate로 검증함
3. **과도한 분절은 의미를 해칠 수 있음**: 너무 잘게 나누면 문맥 보존이 약해짐
   - **해결 방안**: task별 적절한 vocab size를 조정하고 downstream F1로 검증함

## Ⅶ. 적용 사례

- 검색 질의 분석: 형태소 기반 키워드 추출을 수행함, 확인 지표는 검색 정확도임
- 문서 분류: subword tokenizer로 입력을 준비함, 확인 지표는 macro-F1임
- 챗봇/NLU: 개체명과 의도를 인식함, 확인 지표는 intent accuracy와 slot F1임

## Ⅷ. 결론

토크나이징의 핵심은 문자열 분할이 아니라 의미 손실을 최소화하는 입력 단위를 고르는 데 있으므로, 언어 특성과 모델 구조를 함께 고려해야 함.
