## 미리 알고가기

- 소스 코딩: 정보원의 중복을 제거해 전송 비트 수를 줄이는 부호화임
- 채널 코딩: 잡음 오류를 검출·정정하도록 중복 비트를 추가하는 부호화임
- 엔트로피: 소스 코딩이 도달하려는 평균 비트 수의 하한임
- 채널 용량: 주어진 채널에서 오류 확률을 충분히 낮춰 전송할 수 있는 정보율 상한임
- 코드율: 전체 코드 비트 중 실제 정보 비트가 차지하는 비율임

## 작성 근거(검토용)

- 129회 기출 비교 키워드이므로 두 기술의 목적·중복 처리·이론 한계를 같은 축으로 배열함
- 031번 정보이론과 겹치지 않도록 실제 부호화 계층과 송수신 순서를 중심으로 작성함
- 구성요소는 송신·수신 파이프라인을 따라 배치해 부호화와 복호 순서가 보이게 함
- 압축과 오류 정정의 상충은 비교표의 판단 기준을 운영 조건으로 연결함
- 결론은 두 기술 중 우열이 아니라 압축 이득과 오류 보호 비용의 조정이라는 출제 의도를 정리함

## Ⅰ. 개요

- **정의/개념**: 소스 코딩은 정보원의 중복을 제거해 비트 수를 줄이고, 채널 코딩은 검사 비트를 추가해 전송 오류를 검출·정정하는 부호화 계층임
- **배경/필요성**: 제한된 대역폭에서 전송 효율과 복원 신뢰성 확보를 위해 압축과 오류 제어 부호화가 필요함

## Ⅱ. 특징

- 소스 코딩은 불필요한 중복을 제거해 평균 비트 수를 낮춤
- 채널 코딩은 의도적 중복을 추가해 오류 복원력을 높임
- 두 방식의 이론 기준은 각각 엔트로피와 채널 용량임
- 압축률과 오류 정정 강도는 전체 지연·처리량과 함께 조정됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 소스 코딩 | 채널 코딩 |
|:---|:---|:---|
| 목적 | 데이터량 감소 | 전송 오류 제어 |
| 중복 처리 | 통계적 중복 제거 | 검사 중복 추가 |
| 이론 한계 | 엔트로피 | 채널 용량 |
| 대표 기술 | 허프만·RLE·MPEG | 해밍·Reed-Solomon·LDPC |
| 대표 적용 사례 | 이미지·영상·문서 압축 | 메모리·무선·위성 전송 오류 제어 |
| 주요 지표 | 압축률·왜곡률 | 비트 오류율(BER)·프레임 오류율(FER)·코드율 |

> 요약: 소스 코딩은 비트를 줄이고, 채널 코딩은 남은 비트를 보호함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정보원 | 원본 메시지를 만들며 통계적 중복을 가짐 |
| 소스 부호기 | 압축을 수행해 전송할 비트 수를 줄임 |
| 채널 부호기 | 오류 검출·정정 비트를 추가함 |
| 잡음 채널 | 신호 감쇠와 간섭으로 오류를 발생시킴 |
| 복호기 | 채널 오류를 먼저 고친 뒤 압축을 해제함 |

```text
송신: 정보원 -> 소스 부호기 -> 채널 부호기 -> 잡음 채널
수신: 수신기 <- 소스 복호기 <- 채널 복호기 <- 수신 신호
```

> 요약: 송신 측은 압축 후 보호 비트를 붙이고 수신 측은 오류 정정 후 압축을 해제함.

## Ⅵ. 실무 사례

1. 객체 스토리지는 원본을 압축한 뒤 복구용 중복을 추가하고 압축 후 저장량·복구 성공률을 확인함
2. 실시간 미디어 플랫폼은 소스 압축률과 오류 정정 코드율을 조정하고 종단 지연·오류 복구율을 확인함

## Ⅶ. 결론

- 소스 코딩은 중복을 제거하고 채널 코딩은 복구용 중복을 추가하므로 압축률과 코드율을 대역폭·지연 조건에 맞춰 조정해야 함
