# 소스 코딩 vs 채널 코딩 (Source Coding vs Channel Coding)

## 1. 개요

- **정의/개념**: 소스 코딩은 정보원의 중복을 제거해 데이터량을 줄이는 과정이고, 채널 코딩은 전송 오류를 견디기 위해 제어 중복을 추가하는 과정이다.
- **배경/필요성**: 통신·저장 시스템은 효율과 신뢰성을 동시에 요구하므로, 압축을 위한 중복 제거와 오류 제어를 위한 중복 추가를 목적별로 구분해야 한다.

두 코딩은 모두 비트열을 바꾸지만 방향이 반대이다. 소스 코딩은 줄이고, 채널 코딩은 보호하기 위해 늘린다.

## 2. 특징 및 비교

| 구분 | 소스 코딩 | 채널 코딩 |
|---|---|---|
| 목적 | 중복 제거, 압축 | 오류 검출·정정 |
| 이론 기준 | 엔트로피 | 채널 용량 |
| 대표 기법 | Huffman, RLE, LZ | Hamming, CRC, LDPC |
| 성능 지표 | 압축률, 복원 품질 | BER, FER, 복구율 |
| 위치 | 전송 전 데이터량 축소 | 채널 전후 신뢰성 보강 |

선택 기준은 데이터 중복성, 채널 오류율, 지연 허용량, 복원 손실 허용 여부이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Source Encoder | 데이터 중복 제거 | 압축률 |
| Channel Encoder | 오류 제어 비트 추가 | 신뢰성 |
| Channel | 잡음이 존재하는 전송 매체 | 오류 발생 |
| Channel Decoder | 오류 검출·정정 | 복구율 |
| Source Decoder | 압축 해제 | 원본 복원 |

```text
+--------+   +----------+   +----------+   +--------+   +----------+
| 원본   | -> | 소스코딩 | -> | 채널코딩 | -> | 채널   | -> | 복호/복원 |
+--------+   +----------+   +----------+   +--------+   +----------+
             중복 제거       보호 중복 추가      잡음
```

이 흐름을 잡아야 압축률과 오류율을 같은 지표로 착각하지 않고 각 단계의 목적을 분리할 수 있다.

## 4. 문제점 및 개선방안

1. **목적 혼동**
   - 압축 기술로 오류를 정정하거나 오류 정정 코드로 데이터량 절감을 기대하면 설계가 틀어진다.
   - **개선방안**: 엔트로피 기반 압축 영역과 채널 용량 기반 보호 영역을 분리한다.

2. **과도한 압축으로 오류 취약**
   - 압축된 비트열은 일부 손상에도 복호 실패가 커질 수 있다.
   - **개선방안**: 블록화, checksum, 채널 코딩을 압축 후 단계에 배치한다.

3. **채널 코딩 오버헤드**
   - 보호 비트를 과도하게 추가하면 유효 전송률이 낮아진다.
   - **개선방안**: 채널 상태에 맞춰 adaptive coding rate를 적용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 무선 통신 | 음성·영상 압축 후 오류 정정 코드 적용 | BER, bitrate |
| 저장장치 | 데이터 압축과 ECC를 함께 적용 | 저장률, 복구율 |
| 스트리밍 | 코덱 압축과 FEC를 네트워크 상태에 맞게 조정 | 지연, 재전송률 |

## 6. 결론

소스 코딩과 채널 코딩은 모두 정보 표현을 바꾸지만 목적이 정반대이다. 중복 제거와 중복 추가의 방향을 먼저 고정하고, 엔트로피와 채널 용량을 판단 기준으로 연결해야 통신 시스템 설계 논리가 흔들리지 않는다.
