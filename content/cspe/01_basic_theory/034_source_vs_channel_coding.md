## 미리 알고가기

- **중복성(Redundancy)**: 데이터 내에서 예측 가능한 부분. 소스 코딩은 이를 제거하여 효율을 높이고, 채널 코딩은 이를 의도적으로 추가하여 신뢰성을 높임
- **엔트로피(Entropy)**: 정보원이 담고 있는 실제 정보량의 최소 단위. 소스 코딩이 도달하고자 하는 이상적인 압축 하한선임
- **채널 용량(Channel Capacity)**: 잡음이 있는 채널에서 오류 없이 전송 가능한 최대 정보량. 채널 코딩이 넘지 말아야 할 전송 상한선임

## 1. 개요

- **정의/개념**: 소스 코딩(Source Coding)은 정보원에서 발생하는 중복된 데이터를 제거하여 데이터량을 축소하는 압축 과정이며, 채널 코딩(Channel Coding)은 통신 채널의 잡음에 대비해 데이터에 검출·정정용 비트를 추가하여 신뢰성을 확보하는 보호 과정임
- **배경/필요성**: 디지털 통신 시스템은 한정된 대역폭과 전력을 사용하여 데이터를 빠르고 정확하게 전달해야 함. 하지만 압축을 너무 세게 하면(소스 코딩) 비트 하나만 깨져도 복원이 불가능해지고, 반대로 보호를 너무 두껍게 하면(채널 코딩) 실제 데이터보다 검사 비트가 더 많아져 효율이 급감함. 따라서 데이터 발생원(Source)에서는 낭비 요소를 걷어내고, 전송 통로(Channel)에서는 필요한 만큼의 안전장치를 덧붙이는 계층적 접근이 필수적임

## 2. 특징 및 비교

### 가. 소스 코딩과 채널 코딩의 핵심 대비

| 구분 | 소스 코딩 (압축) | 채널 코딩 (오류 제어) |
|:---|:---|:---|
| 주요 목적 | 데이터 전송/저장 효율성 극대화 | 전송 신뢰성 및 무결성 확보 |
| 중복성 처리 | 불필요한 중복(Redundancy) 제거 | 의도적/수학적 중복 추가 |
| 비트열 변화 | 입력보다 출력 비트 수가 줄어듦 | 입력보다 출력 비트 수가 늘어남 |
| 관련 정리 | 섀넌의 소스 코딩 정리 (엔트로피) | 섀넌의 채널 코딩 정리 (용량) |
| 대표 알고리즘 | Huffman, LZ77, JPEG, MPEG | Hamming, CRC, LDPC, Turbo Code |
| 확인 지표 | 압축률, 복원 화질(PSNR) | 비트 오류율(BER), 복구 성공률 |

> 요약: 소스 코딩은 엔트로피 하한까지 줄이는 '다이어트'이며, 채널 코딩은 채널 용량 내에서 입히는 '갑옷'임

### 나. 두 기술의 트레이드오프 관계
- **효율 vs 신뢰**: 소스 코딩을 강화할수록 효율은 높아지나 채널 잡음에 취약해짐
- **오버헤드 vs 복구력**: 채널 코딩의 중복 비트가 많을수록 복구력은 좋아지나 유효 전송 속도는 낮아짐

## 3. 구성요소/구조

### 가. 통신 시스템에서의 계층적 처리 구조

```text
[정보원] -> [소스 인코더] -> [채널 인코더] -> [변조/채널] -> [채널 디코더] -> [소스 디코더] -> [복원]
            (중복 제거)      (오류 방어)     (잡음 유입)     (오류 정정)      (압축 해제)
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 소스 인코더 | 기호 간 상관관계나 출현 빈도를 분석해 압축 | 무손실/손실 압축 선택 가능 |
| 채널 인코더 | 데이터에 패리티 또는 체크섬 비트 결합 | 블록 부호 또는 컨볼루션 부호 적용 |
| 잡음 채널 | 신호 감쇄, 열잡음, 간섭이 발생하는 구간 | 섀넌 한계가 결정되는 물리적 환경 |
| 채널 디코더 | 수신된 비트열에서 오류 위치 탐색 및 정정 | 신뢰도 높은 원본 비트열 복원 |
| 소스 디코더 | 압축 부호를 다시 원래의 심벌로 환원 | 원본과의 정합성 확인 |

> 요약: 소스 코딩이 '무엇을 보낼지'를 결정하면, 채널 코딩은 '어떻게 무사히 보낼지'를 책임지는 구조임

## 4. 문제점 및 개선방안

1. **압축 데이터의 오류 민감도 증폭**: 소스 코딩으로 중복이 제거된 데이터는 비트 하나가 정보 전체를 대표하므로, 작은 오류에도 전체 프레임이 깨질 수 있음
   - **개선방안**: 중요도가 높은 상위 비트(MSB)나 헤더 구간에만 더 강한 채널 코딩을 적용하는 '차등 오류 보호(UEP, Unequal Error Protection)' 기법을 도입함

2. **고정 코딩률로 인한 자원 낭비**: 채널 상태가 좋은데도 낮은 속도의 채널 코딩을 고집하면 불필요한 중복 비트 전송으로 대역폭이 낭비됨
   - **개선방안**: 채널 품질(CSI)을 실시간 측정하여 변조 방식과 코딩률을 동적으로 바꾸는 '적응형 변조 및 부호화(AMC)'를 적용함

3. **연산 지연 및 하드웨어 부담**: 강력한 압축과 오류 정정 알고리즘은 복잡한 연산을 수반하여 실시간 서비스의 지연(Latency)을 유발함
   - **개선방안**: 전용 DSP 또는 FPGA 가속기를 활용하고, 지연 민감도에 따라 코딩 블록 크기를 유연하게 조절함

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 4G/5G 무선 통신 | 비디오 코덱(H.265)으로 압축 후 터보/LDPC 코드로 무선 구간 보호 | 유효 데이터 속도, 지연 시간 |
| 위성 방송 (DVB-S2) | 대역폭 효율을 위해 다차 변조와 강력한 FEC(BCH + LDPC)를 결합 | 수신 신호 강도, 비트 오류율 |
| 테이프/디스크 저장 | 데이터 반복 제거 후 리드-솔로몬(RS) 코드로 물리적 긁힘 등에 대비 | 저장 밀도, 데이터 보존 수명 |

> 요약: 소스 코딩으로 저장/전송 비용을 줄이고, 채널 코딩으로 유실 비용을 막는 것이 모든 데이터 엔지니어링의 기본임

## 6. 결론

소스 코딩과 채널 코딩은 디지털 시스템의 효율과 신뢰라는 두 마리 토끼를 잡기 위한 상호 보완적인 필수 기술임. 섀넌이 제시한 엔트로피와 채널 용량이라는 두 극점 사이에서 최적의 균형점을 찾는 것이 엔지니어링의 핵심 과제임.

기술사는 단순히 알고리즘을 나열하는 것을 넘어, 서비스의 성격(실시간성 vs 무결성)과 물리적 채널의 특성을 고려하여 소스 코딩의 압축 강도와 채널 코딩의 복구 능력을 최적으로 배분할 수 있는 설계 역량을 갖추어야 함. 향후 AI 기반의 인공 신경망 코덱과 초고성능 오류 정정 부호의 등장은 이 두 기술의 경계를 더욱 좁히며 시스템 성능을 섀넌 한계치까지 밀어붙일 것임.
