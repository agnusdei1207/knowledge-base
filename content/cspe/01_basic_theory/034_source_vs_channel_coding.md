## 미리 알고가기

- 소스 코딩: 정보원의 중복을 제거해 전송 비트 수를 줄이는 부호화임
- 채널 코딩: 잡음 오류를 검출·정정하도록 중복 비트를 추가하는 부호화임
- 엔트로피: 소스 코딩이 도달하려는 평균 비트 수의 하한임
- 채널 용량: 채널 코딩 후 오류 없이 보낼 수 있는 전송률 상한임
- 코드율: 전체 코드 비트 중 실제 정보 비트가 차지하는 비율임

## Ⅰ. 개요

- **정의/개념**: 소스 코딩은 압축으로 효율을 높이고, 채널 코딩은 오류 제어로 신뢰성을 높이는 부호화 계층임
- **배경/필요성**: 제한된 대역폭에서 데이터를 적게 보내면서도 잡음 환경에서 정확히 복원해야 하므로 두 부호화가 함께 필요함

## Ⅱ. 특징

- 소스 코딩은 불필요한 중복을 제거해 평균 비트 수를 낮춤
- 채널 코딩은 의도적 중복을 추가해 오류 복원력을 높임
- 두 방식의 이론 기준은 각각 엔트로피와 채널 용량임
- 압축률과 오류 정정 강도는 전체 지연·처리량과 함께 조정됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 소스 코딩 | 채널 코딩 |
|:---|:---|:---|
| 목적 | 데이터량 감소 | 전송 오류 제어 |
| 중복 처리 | 통계적 중복 제거 | 검사 중복 추가 |
| 이론 한계 | 엔트로피 | 채널 용량 |
| 대표 기술 | Huffman, RLE, MPEG | Hamming, Reed-Solomon, LDPC |
| 주요 지표 | 압축률, 왜곡률 | BER, FER, 코드율 |
| 실패 영향 | 품질 저하, 복호 실패 | 비트 오류, 재전송 증가 |

> 요약: 소스 코딩은 비트를 줄이고, 채널 코딩은 남은 비트를 보호함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정보원 | 원본 메시지를 만들며 통계적 중복을 가짐 |
| 소스 부호기 | 압축을 수행해 전송할 비트 수를 줄임 |
| 채널 부호기 | 오류 검출·정정 비트를 추가함 |
| 잡음 채널 | 신호 감쇠와 간섭으로 오류를 발생시킴 |
| 복호기 | 채널 오류를 먼저 고친 뒤 압축을 해제함 |

```text
송신: 정보원 -> 소스 부호기 -> 채널 부호기 -> 잡음 채널
수신: 수신기 <- 소스 복호기 <- 채널 복호기 <- 수신 신호
```

> 요약: 송신 측은 압축 후 보호 비트를 붙이고 수신 측은 오류 정정 후 압축을 해제함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+   +----------+   +----------+   +----------+   +----------+
| 중복 제거 | -> | 보호비트 추가 | -> | 채널 전송 | -> | 오류 정정 | -> | 원본 복원 |
+----------+   +----------+   +----------+   +----------+   +----------+
```

1. 정보원의 통계 특성을 분석해 압축 부호를 선택함
2. 압축 비트열에 채널 상태에 맞는 오류 정정 부호를 붙임
3. 수신 측은 신드롬이나 패리티로 오류 위치를 추정함
4. 오류 정정 후 소스 복호를 수행해 원본 메시지를 복원함

> 요약: 소스 코딩과 채널 코딩은 송신 순서와 반대인 복호 절차까지 함께 설계해야 함.

## Ⅵ. 실무 적용 및 유의점

1. 압축률을 높이면 오류 전파 위험이 커지므로 FEC 강도와 재전송 정책을 BER·품질 지표로 함께 조정함
2. 실시간 음성·영상은 지연 예산이 작으므로 압축률, 코드율, 패킷 손실률을 함께 조정함

## Ⅶ. 결론

- 소스 코딩과 채널 코딩은 효율과 신뢰성을 나누어 책임지며, 실제 시스템은 압축 이득과 오류 보호 비용의 균형으로 설계해야 함
