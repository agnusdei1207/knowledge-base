## 미리 알고가기

- 소스 코딩: 데이터의 통계적 중복을 제거해 비트 수를 줄이는 압축 부호화임
- 채널 코딩: 잡음 채널에서 오류를 검출·정정하기 위해 중복을 추가하는 부호화임
- 엔트로피: 소스 코딩에서 달성 가능한 평균 코드 길이의 이론적 하한임
- 채널 용량: 채널 코딩에서 신뢰 전송 가능한 최대 정보율의 이론적 상한임
- 분리 정리: 이상 조건에서 소스 코딩과 채널 코딩을 독립적으로 최적화할 수 있다는 정리임

## Ⅰ. 개요

- **정의**: 소스 코딩과 채널 코딩은 각각 중복 제거와 오류 제어를 통해 제한된 대역폭에서 정보량과 전송 신뢰성을 조정하는 부호화 기법임
- **배경/필요성**: 통신 시스템은 비트 수를 줄여 효율을 높이는 동시에 잡음으로 인한 오류를 줄여야 하므로, 중복을 제거하는 단계와 필요한 중복을 다시 추가하는 단계를 목적별로 구분해야 함.
- **비유**: 짐을 먼저 최소한으로 압축해 포장한 뒤, 깨지지 않도록 완충재를 넣어 배송하는 과정과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 코딩의 목적 차이 설명 | 중복 제거 vs 중복 추가, 엔트로피 vs 채널 용량 | 둘 다 압축으로 설명 |
| 통신 시스템 내 위치 이해 | 소스-채널 분리, 오류정정, 전송률 | 순서와 역할 혼동 |

> 요약: 소스 코딩은 비트 수를 줄이고 채널 코딩은 오류에 견디도록 중복을 넣는 상반 목적의 부호화임.

## Ⅱ. 특징/비교

| 판단 기준 | 소스 코딩 | 채널 코딩 |
|:---|:---|:---|
| 목적 | 데이터 중복 제거와 압축률 향상 | 오류 검출·정정과 신뢰도 향상 |
| 이론 기준 | 엔트로피 H(X), 평균 코드 길이 | 채널 용량 C, BER/FER |
| 대표 기법 | 허프만, 산술 코딩, RLE, LZ | 해밍, BCH, Reed-Solomon, LDPC |
| 중복 처리 | 불필요한 중복을 제거함 | 오류 복구용 중복을 추가함 |
| 선택 기준 | 저장·전송량 절감이 우선일 때 | 잡음 채널 신뢰성이 우선일 때 |

- **순서 기준**: 일반적으로 소스 코딩으로 압축한 뒤 채널 코딩으로 오류 보호를 적용함.
- **한계 기준**: 전송률은 소스 압축 후에도 채널 용량보다 낮아야 신뢰 전송이 가능함.
- **예외 기준**: 초저지연·열악한 채널에서는 joint source-channel coding을 검토할 수 있음.

> 요약: 소스 코딩과 채널 코딩은 중복을 다루는 방향이 반대이며, 시스템 목표가 효율인지 신뢰성인지에 따라 설계 기준이 달라짐.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+      +------------+
| Source     | ---> | Source     | ---> | Channel    | ---> | Noisy      |
| Data       |      | Encoder    |      | Encoder    |      | Channel    |
+------------+      +------------+      +------------+      +------------+
       ^                                                          |
       |                                                          v
+------------+      +------------+      +------------+      +------------+
| Recovered  | <--- | Source     | <--- | Channel    | <--- | Received   |
| Data       |      | Decoder    |      | Decoder    |      | Bits       |
+------------+      +------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정보원 | 압축 전 원본 데이터와 확률 분포를 제공함 | 보낼 짐 |
| 소스 인코더 | 중복을 제거해 평균 비트 수를 줄임 | 짐 압축기 |
| 채널 인코더 | 오류 검출·정정을 위한 검사 비트나 코드를 추가함 | 완충재 넣기 |
| 잡음 채널 | 전송 중 비트 오류, 손실, 왜곡을 일으킬 수 있는 매체임 | 흔들리는 배송로 |
| 복호기 체인 | 채널 오류를 먼저 정정하고 소스 압축을 풀어 원본을 복원함 | 포장 해제와 물품 확인 |

> 요약: 통신 체인은 소스 인코더로 비트를 줄이고 채널 인코더로 보호한 뒤, 수신 측에서 역순으로 오류 정정과 압축 해제를 수행함.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Compress   | ---> | Protect    | ---> | Transmit   | ---> | Decode     |
| Source     |      | Channel    |      | Noisy Link |      | Reverse    |
+------------+      +------------+      +------------+      +------------+
```

1. **소스 분석**: 원본 데이터의 확률 분포와 허용 손실 여부를 판단해 소스 코딩 방식을 선택함.
2. **압축 수행**: 엔트로피에 가까운 평균 코드 길이를 목표로 중복을 제거함.
3. **채널 보호**: 채널 오류율과 용량을 기준으로 오류정정 코드율과 부호 길이를 정함.
4. **복호·검증**: 수신 측에서 오류를 정정한 뒤 압축을 해제하고 BER, FER, 복원 품질을 확인함.

> 요약: 전체 흐름은 압축으로 비트를 줄이고 오류정정으로 보호한 뒤, 수신 측에서 역순으로 복원하고 품질을 검증하는 과정임.

## Ⅴ. 문제점

- **P1 목적 혼동**: 압축 단계에서 모든 중복을 제거한 뒤 채널 보호를 생략하면 작은 비트 오류도 복원 실패로 이어질 수 있음.
- **P2 분리 정리 조건 불일치**: 짧은 패킷, 초저지연, 시간 변화 채널에서는 소스와 채널을 독립 최적화해도 전체 최적이 아닐 수 있음.
- **P3 코드율 부적합**: 압축 후 전송률과 채널 코드율이 채널 용량·오류율과 맞지 않으면 지연이나 재전송이 증가함.

> 요약: 두 코딩은 목적, 이론 조건, 코드율을 구분하지 않으면 효율과 신뢰성 중 하나가 쉽게 깨짐.

## Ⅵ. 개선방안

- **P1 대응**: 압축 후 반드시 채널 보호 수준을 별도로 산정하고 중요 비트에는 unequal error protection을 적용함. (확인: 복원 실패율)
- **P2 대응**: 지연과 패킷 길이가 제한된 서비스는 joint source-channel coding 또는 cross-layer 설계를 검토함. (확인: end-to-end latency)
- **P3 대응**: 채널 상태 추정 기반 adaptive coding and modulation으로 코드율과 변조 방식을 조정함. (확인: BER과 throughput)

> 요약: 소스와 채널 코딩은 기본적으로 분리하되, 짧은 지연·변동 채널에서는 공동 최적화와 적응형 코드율 제어가 필요함.

## Ⅶ. 전망

- **발전 방향**: 5G/6G, 위성통신, IoT, 실시간 스트리밍에서 압축 효율과 오류 복구의 공동 최적화 요구가 커질 전망임.
- **기술사적 판단**: 저장 비용이 큰지, 전송 오류가 큰지, 지연 제약이 강한지에 따라 두 코딩의 우선순위와 코드율을 결정해야 함.
- **기술사 제언**: 답안에서는 중복 제거와 중복 추가의 반대 방향을 먼저 고정하고, 엔트로피와 채널 용량을 판단 기준으로 연결해야 함.
