## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 소스 코딩은 데이터 중복을 제거하여 압축하는 기법이고, 채널 코딩은 전송 오류에 대비하여 중복(Redundancy)을 추가하는 기법임 |
| **배경/필요성** | 제한된 채널 대역폭에서 최대 정보를 전송하려면 소스 압축이, 잡음 채널에서 무오류 전송을 보장하려면 오류 정정이 필요함 |
| **출제 의도** | 소스 코딩과 채널 코딩의 상반된 목적과 분리 정리(Separation Theorem)를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 소스코딩  | --> |  채널    | --> | 채널코딩  |
| (압축)   |     | (잡음)   |     | (오류정정)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 소스 코딩 | 데이터의 통계적 중복을 제거하여 비트율을 엔트로피 H에 근접시킴 | 짐을 최소로 꾸리기 |
| 채널 코딩 | 데이터에 검사 비트를 추가하여 전송 오류를 검출·정정함 | 짐에 완충재 넣기 |
| 분리 정리 | 소스 코딩과 채널 코딩을 독립적으로 최적 설계해도 전체 최적성이 보장됨 | 짐 꾸리기와 완충재를 따로 최적화해도 OK |

> 요약: 소스 코딩(중복 제거) → 채널(잡음) → 채널 코딩(중복 추가)으로, 분리 정리에 의해 독립 설계 가능함.

## Ⅲ. 절차
```
+------------+     +------------+
| 소스압축   | --> | 채널코딩   |
| (허프만등) |     | (LDPC등)  |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 소스복원   | <-- | 채널디코딩 |
| (복원)     |     | (오류정정) |
+------------+     +------------+
```

1. 소스 압축: 허프만·LZ77·산술 코딩으로 데이터를 엔트로피 근처까지 압축함
2. 채널 코딩: LDPC·Turbo·Polar 코드로 검사 비트를 추가하여 채널 용량 C 근처까지 보호함
3. 채널 전송·수신: 잡음 채널을 통해 데이터를 전송하고 수신함
4. 채널 디코딩 → 소스 복원: 오류를 정정한 후 소스 디코딩으로 원본 데이터를 복원함

> 요약: 소스 압축 → 채널 코딩 → 전송 → 디코딩 → 복원의 파이프라인으로 데이터를 전송함.

## Ⅳ. 문제점
- 분리 정리 한계: 유한 블록·지연 제약에서 분리 설계가 최적이 아닐 수 있음
- 소스-채널 불일치: 압축 후 남은 비트 하나의 오류가 전체 복원에 영향을 줌(오류 전파)
- 실시간 제약: 긴 블록 코딩은 지연이 커서 실시간 통신에 부적합함

## Ⅴ. 개선방안
- (단기) 불균등 오류 보호(UEP): 중요 비트에 더 강한 채널 코딩을 적용함
- (중기) 공동 소스-채널 코딩(JSCC): 소스·채널을 통합 설계하여 유한 블록 환경의 성능을 개선함
- (장기) 딥러닝 JSCC: 오토인코더 기반 End-to-End 코딩으로 소스·채널을 동시 최적화함

## Ⅵ. 전망
- 5G에서 LDPC(데이터)·Polar(제어) 코드가 채널 코딩 표준이며, 6G에서 딥러닝 기반 공동 소스-채널 코딩(DeepJSCC)이 차세대 전송 패러다임으로 연구되고 있음
