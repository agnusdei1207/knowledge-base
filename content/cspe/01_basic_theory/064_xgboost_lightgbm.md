## 미리 알고가기

- GBDT: 이전 트리의 예측 오류 방향을 다음 트리가 보정하는 그래디언트 부스팅 트리임
- 잔차: 실제값과 현재 예측값의 차이이며 다음 트리가 학습할 보정 대상임
- 학습률: 새 트리의 기여도를 줄여 과적합을 늦추는 축소 계수임
- Level-wise: 같은 깊이의 노드를 균형 있게 확장하는 트리 성장 방식임
- Leaf-wise: 손실 감소가 가장 큰 리프를 우선 확장하는 트리 성장 방식임

## Ⅰ. 개요

- **정의**: XGBoost와 LightGBM은 손실 함수의 기울기와 트리 정규화 기준으로 잔차를 순차 보정하는 GBDT 구현체임
- **배경/필요성**: 기존 GBM은 순차 학습으로 정확도는 높지만 대규모 데이터와 다수 피처에서 학습 시간이 길고 과적합 제어가 어려웠음
- **비유**: 시험에서 틀린 문제를 매 회차 집중 보정하되, 복습량과 보폭을 조절해 과도한 암기를 막는 방식과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| XGBoost와 LightGBM 차이 설명 | Level-wise, Leaf-wise, histogram 분할 | 둘을 같은 GBM 구현체로만 처리 |
| 과적합 제어 원리 설명 | 학습률, 정규화, 조기 종료 | n_estimators 증가만 장점으로 서술 |

> 요약: XGBoost와 LightGBM은 잔차를 순차 보정하는 부스팅 구조에 정규화와 분할 최적화를 결합한 정형 데이터 대표 모델임

## Ⅱ. 특징/비교

| 판단 기준 | XGBoost | LightGBM |
|:---|:---|:---|
| 트리 성장 | Level-wise에 가까운 균형 성장을 유지함 | Leaf-wise로 손실 감소가 큰 리프를 우선 확장함 |
| 속도·메모리 | 균형 성장과 정밀 분할로 학습 시간과 메모리 사용량이 상대적으로 큼 | histogram, GOSS, EFB로 대용량 학습에 유리함 |
| 과적합 위험 | 균형 성장과 정규화로 통제가 쉬운 편임 | leaf-wise가 깊어지면 소량 데이터에서 과적합 가능성이 큼 |
| 선택 기준 | 과적합 통제와 재현성이 중요한 정형 분석에 적합함 | 대용량·고차원 데이터의 학습 속도가 중요할 때 적합함 |

> 요약: XGBoost는 정규화·결측 처리 제어, LightGBM은 학습 시간과 메모리 절감에 강점이 있어 데이터 규모와 과적합 위험에 따라 선택함

- **공통 강점**: 결측치 자동 분기, 피처 중요도 산출, 비선형 상호작용 학습을 기본 지원함
- **튜닝 핵심**: learning_rate, max_depth 또는 num_leaves, subsample, colsample을 함께 조정해야 함
- **검증 기준**: leaderboard 점수보다 검증셋 누수, 시간 분할, 운영 지연을 함께 봐야 함

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Loss        | ---> | Gradient /  | ---> | New Tree    |
| Function    |      | Residual    |      | Split       |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Regularizer |      | Learning    | ---> | Ensemble    |
| L1/L2/Depth |      | Rate        |      | Prediction  |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 손실 함수 | 예측 오류를 수치화하고 다음 트리가 줄여야 할 방향을 제공함 | 채점표 |
| 그래디언트·잔차 | 현재 모델이 틀린 정도를 나타내며 새 트리의 학습 목표가 됨 | 오답 표시 |
| 트리 분할 전략 | XGBoost는 균형 성장, LightGBM은 손실 감소 리프 우선 성장으로 분기를 정함 | 가지치기 방식 |
| 정규화 항 | 트리 깊이, 리프 수, 가중치 크기에 페널티를 주어 과적합을 억제함 | 과속 방지턱 |
| 학습률 | 새 트리의 보정 크기를 줄여 점진적으로 모델을 갱신함 | 보폭 조절기 |

> 요약: GBDT 구현체는 손실의 기울기를 계산하고 새 트리로 잔차를 보정하되 정규화와 학습률로 복잡도를 통제함

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Init      | --> | Compute   | --> | Grow Tree | --> | Update    |
| Prediction|     | Gradient  |     | by Split  |     | Ensemble  |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
baseline          residual target     best gain split    early stop
```

1. **초기 예측 설정**: 평균값, 로그 오즈 등 단순 기준 예측을 시작점으로 둠
2. **잔차·그래디언트 계산**: 현재 예측과 실제값의 차이를 손실 함수 기준으로 계산함
3. **트리 성장**: 분할 이득이 큰 지점을 찾아 새 트리를 만들고 정규화 조건으로 복잡도를 제한함
4. **모델 갱신·검증**: 학습률을 곱한 새 트리를 기존 모델에 더하고 검증 손실 개선이 멈추면 조기 종료함

> 요약: 초기 모델에서 잔차를 계산하고 새 트리를 추가하는 과정을 반복하되 학습률과 조기 종료로 과적합을 관리함

## Ⅴ. 문제점

- **P1 오적용 과적합**: 소량·노이즈 데이터에 Leaf-wise 성장의 LightGBM을 그대로 적용하면 순차 보정 구조가 실제 신호뿐 아니라 우연한 잔차와 이상치까지 학습함
- **P2 튜닝 복잡도**: 트리 깊이, 리프 수, 학습률, 샘플링 비율이 상호작용해 최적 조합 탐색 비용이 큼
- **P3 범주형·시계열 누수**: 원핫 인코딩, target encoding, 임의 분할 과정에서 미래 정보나 정답 정보가 섞일 수 있음

> 요약: GBDT 운영의 핵심 위험은 잔차 과적합, 파라미터 탐색 부담, 전처리·검증 단계의 데이터 누수임

## Ⅵ. 개선방안

- **P1 대응**: 데이터 규모에 따라 num_leaves 제한 또는 균형 성장 XGBoost를 선택하고 조기 종료, subsample, L1/L2 정규화를 함께 적용함 (확인: 검증 손실 곡선)
- **P2 대응**: 탐색 공간을 축소한 뒤 Optuna 등 베이지안 최적화로 주요 파라미터부터 조정함 (확인: 튜닝 시간 대비 AUC 개선)
- **P3 대응**: 시간 기반 검증, 누수 없는 인코딩, fold 내부 전처리 파이프라인을 적용함 (확인: 운영 데이터 재현 성능)

> 요약: 과적합 제어와 튜닝 자동화는 모델 내부 문제를, 검증 설계는 운영 성능 과대평가 문제를 완화함

## Ⅶ. 전망

- **발전 방향**: 정형 데이터에서는 GBDT가 딥러닝과 결합하거나 AutoML의 기본 탐색 모델로 계속 활용될 전망임
- **기술사적 판단**: 이미지·텍스트 원천 데이터는 딥러닝이 우세하지만, 테이블 데이터와 제한된 학습 비용에서는 GBDT 선택이 합리적임
- **기술사 제언**: 답안에서는 XGBoost와 LightGBM의 분할 전략 차이와 과적합 제어 방안을 동시에 제시해야 함
