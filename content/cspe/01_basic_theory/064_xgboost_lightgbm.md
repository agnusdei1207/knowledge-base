# 📖 【암기용】 개념 완전 이해

> 목적: XGBoost와 LightGBM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 머신러닝의 앙상블(부스팅) 계열을 평정하고 정형 데이터 분석 대회(Kaggle 등)를 휩쓴 최고의 분류·회귀 알고리즘이다.
- **왜 필요한가**: 기존 부스팅 모델(GBM)은 정확도는 높으나 학습 속도가 너무 느리고 과적합에 취약했다. 이를 극복하기 위해 병렬 처리와 분할 최적화를 도입했다.
- **핵심 직관**: 여러 개의 나무(결정 트리)를 순차적으로 만들며 앞선 나무의 '오차'를 다음 나무가 고치는 방식이다. XGBoost는 나무를 한 층씩 꼼꼼하게 만들고(Level-wise), LightGBM은 오차가 큰 가지부터 먼저 깊게 뻗어버린다(Leaf-wise).

## 깊이 이해
- **배경·문제의식**:
  - GBM은 트리를 만들 때마다 모든 데이터를 스캔하여 분할 지점(Split point)을 찾기 때문에 $O(N \log N)$의 연산이 매번 발생해 대용량 데이터 학습이 불가능했다.
- **작동 원리**:
  - **XGBoost (eXtreme Gradient Boosting)**: 병렬 처리 지원, 결측치 자동 처리, 정규화(Regularization)를 추가하여 과적합을 막는다. 나무를 균형 있게 키운다(Level-wise).
  - **LightGBM**: 히스토그램 기반 알고리즘을 사용해 데이터를 구간(Bin)으로 묶어 분할 속도를 획기적으로 높였다. 또한 오차가 큰 잎(Leaf)만 집중적으로 분할하여 비대칭적인 깊은 트리를 만든다(Leaf-wise).
- **비유**: XGBoost는 건물을 한 층씩 튼튼하게 골고루 올리는 건설 방식이고, LightGBM은 급한 곳(오차가 큰 곳)부터 타워 크레인으로 집중 증축하는 방식이다.
- **구체 예시**: 1,000만 건의 신용카드 사기 탐지 데이터 학습 시, XGBoost가 2시간 걸린다면 LightGBM은 메모리 사용량을 절반으로 줄이고 30분 만에 비슷한 정확도로 학습을 끝낸다.
- **흔한 오해·주의점**: LightGBM이 무조건 좋은 것은 아니다. Leaf-wise 방식은 과적합에 취약하므로 데이터가 1만 건 이하로 적을 때는 XGBoost나 Random Forest를 쓰는 것이 안전하다.

## 연결 개념
- Gradient Boosting Machine (GBM) — XGBoost와 LightGBM의 뼈대가 되는 부스팅 알고리즘
- 앙상블 학습 (Ensemble) — 여러 모델을 결합하여 예측 성능을 높이는 기법
- 과적합 (Overfitting) — 훈련 데이터에 너무 맞춰져 새로운 데이터를 예측하지 못하는 상태

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: XGBoost와 LightGBM은 Gradient Boosting 알고리즘의 연산 병목을 병렬 처리와 히스토그램 최적화로 극복한 트리 기반 앙상블 모델이다.
> 2. **가치**: 정형 데이터 분류/회귀 문제에서 최상위 성능(Accuracy, F1-score)을 보장하며, 학습 속도와 메모리 효율을 극대화한다.
> 3. **판단 포인트**: 안정성과 정확도 우선 시 XGBoost를, 10만 건 이상의 대용량 데이터와 학습 시간 단축 요구 시 LightGBM을 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기존 GBM의 한계와 두 모델의 개선 기전 비교 | Level-wise(XGB) vs Leaf-wise(LGBM) 트리 분할 방식 | 단순히 "GBM보다 빠르다" 식 추상 서술 금지 |
| 대용량 정형 데이터 처리 알고리즘 선택 기준 | 히스토그램 기반 분할, GOSS 및 EFB 적용 여부 | 데이터 규모에 따른 과적합 리스크 차이 명시 |

> 요약: 트리 분할 구조의 차이(수평 vs 수직)와 연산 최적화 기법(Exact Greedy vs Histogram)을 명확히 대조해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 결정 트리를 순차적으로 추가하며 잔차(Residual)를 줄여가는 그래디언트 부스팅 머신(GBM)의 고도화 구현체
- 배경: 기존 GBM 알고리즘은 분할 탐색 비용이 크고, 직렬 연산으로 인해 대용량 데이터 학습 시 타임아웃이 발생함
- 필요성: 정칙화(Regularization)를 통한 과적합 방지와 하드웨어 병렬 최적화를 통해 분류/회귀 태스크의 상용화 요건(속도, 정확도)을 충족해야 함

---

## Ⅱ. 구조 및 구성요소

```text
학습 데이터 -> 베이스 모델(트리 1) -> 오차(잔차) 계산 -> 트리를 순차 추가(학습) -> 앙상블 최종 예측
                                     +-> XGB: Level-wise 병렬 분할
                                     +-> LGBM: Leaf-wise + 히스토그램 분할
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 목적 함수 (Objective) | 학습 손실과 정칙화 항(L1, L2)의 합 | 과적합 방지 역할 수행 |
| 노드 분할(Split) | 정보 획득량(Information Gain) 최대화 지점 탐색 | Exact Greedy 또는 Histogram |
| 트랜잭션 병렬화 | 특징 정렬(Feature Sorting) 및 블록 단위 메모리 할당 | XGBoost의 속도 개선 코어 |
| EFB (Exclusive Feature Bundling) | 배타적 희소 특징을 단일 특징으로 병합 | LightGBM의 메모리 압축 |

> 요약: 모델은 목적 함수를 최소화하는 방향으로 트리를 추가하며, 분할 탐색과 메모리 병합 기법으로 성능을 극대화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
초기 예측값 설정 -> 기울기(Gradient) 도출 -> 히스토그램/정렬 기반 분할 노드 탐색 -> 트리 성장 -> 모델 업데이트
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 부스팅 초기화 및 Gradient 계산 | 잔차(Residual) 산출 |
| 2 | 분할 임계값 탐색 | 데이터 스캔 복잡도 $O(\#data \times \#feature)$ 감소 |
| 3 | 최적 노드 분할 적용 | XGB (Level-wise) / LGBM (Leaf-wise) 적용 |
| 4 | 리프 노드 가중치 업데이트 및 트리 추가 | Learning rate(eta) 반영 |

> 요약: 현재 모델의 예측 오차를 미분하여 기울기를 구하고, 이 오차를 줄이도록 트리 구조를 최적화하여 갱신한다.

---

## Ⅳ. 특징

| 구분 | XGBoost (eXtreme Gradient Boosting) | LightGBM |
|:---|:---|:---|
| 성장 방식 | Level-wise (균형 우선 성장) | Leaf-wise (손실 최대 리프 우선 분할) |
| 노드 분할 탐색 | Exact Greedy 또는 히스토그램 근사 | 히스토그램 기반 특화 |
| 데이터 제약 | 소규모 데이터에서도 과적합에 강함 | 1만 건 이하 데이터 학습 시 과적합 취약 |

> 요약: XGBoost는 안정적인 균형 구조로 정확도를 담보하고, LightGBM은 비대칭 성장을 통해 연산 시간을 압축한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존 Random Forest | XGBoost | LightGBM |
|:---|:---|:---|:---|
| 학습 방식 | 배깅 (독립적 다수결) | 부스팅 (순차적 오차 보완) | 부스팅 + 히스토그램 + GOSS |
| 주요 강점 | 병렬 처리 용이, 하이퍼파라미터 둔감 | 강력한 성능, 결측치 자동 대처 | 압도적 속도, 메모리 사용량 최소화 |
| 선택 기준 | 베이스라인 모델 구축 | 10만 건 미만 정형 데이터 정밀 분류 | 수백만 건 이상 대용량 추천/탐지 |

> 요약: 데이터 규모가 작으면 Random Forest/XGBoost를, 대용량 상용 트래픽에는 LightGBM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과적합(Overfitting) | Leaf-wise 성장에 따른 과도한 깊이 (LGBM) | `max_depth`, `num_leaves` 파라미터 제한 통제 | Train/Test AUC 격차 |
| 리소스 부족 | One-hot 인코딩에 의한 희소 특징 차원 폭발 | LGBM 내장 카테고리 피처 처리 활성화 (EFB) | 학습 시 Peak RAM |
| 불균형 데이터 편향 | 사기 탐지 등에서 소수 클래스 예측 실패 | `scale_pos_weight` 조정, Focal Loss 적용 | F1-score, Recall |

> 요약: 트리 깊이 제한과 내장 카테고리 최적화를 통해 과적합과 차원 폭발 리스크를 제어한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 분류 정확도 | ROC-AUC 0.85 이상, F1 0.80 이상 | 교차 검증 (K-Fold), 혼동 행렬 |
| 학습 효율성 | 100만 건 데이터 기준 10분 이내 학습 완료 | Time 모니터링, 프로파일링 |
| 추론 지연시간 | 단건 예측 지연 p95 10ms 이하 | 추론 서버 API 벤치마크 테스트 |

> 요약: 대규모 부스팅 모델 도입 시에는 ROC-AUC 지표 외에 메모리 피크와 추론 지연시간을 반드시 통제해야 전체 파이프라인이 최적화된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 금융 사기 탐지(FDS): XGBoost를 적용하여 결측치가 많은 금융 트랜잭션 데이터를 전처리 없이 학습하고, 1만 건 미만의 소수 이상 거래 탐지율(Recall)을 90% 이상 확보한다.
2. 커머스 클릭 예측(CTR): 1,000만 건 이상의 일일 로그 데이터 학습 속도 병목을 해결하기 위해, LightGBM을 도입하고 `categorical_feature` 내장 옵션을 통해 학습 메모리를 50% 절감한다.
3. 파라미터 자동 최적화: Optuna 또는 Hyperopt를 MLOps 파이프라인에 통합하여, XGBoost의 `eta`와 `max_depth`, LightGBM의 `num_leaves`를 베이지안 최적화 기반으로 자동 튜닝한다.

**결론 (2줄):**
- 기술사 판단: 정형 데이터(Tabular Data)의 분류/회귀 문제에서는 딥러닝보다 트리 기반 부스팅(XGBoost, LightGBM)이 학습 효율과 해석력(Feature Importance) 측면에서 최우선 도입 대상이다.
- 향후 방향: 최근에는 GPU 가속 지원(cuML)과 XGBoost/LightGBM을 통합하여 활용하는 앙상블 스태킹(Stacking) 방식이 상용 시스템의 표준 베이스라인으로 자리 잡고 있다.
