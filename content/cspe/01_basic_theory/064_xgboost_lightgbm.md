# 📖 【암기용】 개념 완전 이해

> 목적: XGBoost와 LightGBM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **그래디언트 부스팅**(Gradient Boosting Machine, GBM)이 매 트리마다 전체 데이터를 정렬해 분할점을 찾느라 대용량 데이터에서 느려지는 연산 병목을, **병렬 처리**·**근사 분할 알고리즘**·**정규화**로 해결한 트리 기반 부스팅 구현체가 XGBoost와 LightGBM이다.
- **왜 필요한가**: 063 앙상블의 부스팅은 순차 학습이라 원래 느리고, 게다가 각 분할 지점을 찾을 때마다 데이터를 정렬(O(N log N))해야 해서 수백만 건 데이터에서는 학습이 며칠씩 걸릴 수 있었다. 이 병목을 뚫지 않으면 부스팅은 실무에서 쓸 수 없었다.
- **핵심 직관**: 두 방식 모두 "앞 트리의 오차(잔차)를 다음 트리가 메운다"는 부스팅 원리는 같다. 차이는 트리를 키우는 순서다 — XGBoost는 한 층씩 골고루 넓게 키우고(Level-wise), LightGBM은 오차가 가장 큰 가지 하나를 골라 계속 깊게 파고든다(Leaf-wise).

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| Gradient Boosting(GBM) | 이전 모델의 오차(그래디언트)를 다음 트리의 학습 목표로 삼아 순차적으로 이어 붙이는 부스팅 방식 | 오답을 계속 물려받아 채점하는 이어달리기 |
| 목적함수(Objective) | 손실(예측 오차) + 정규화 항(트리 복잡도 페널티)의 합 — 이걸 최소화하도록 트리를 키움 | 시험 점수에서 반칙(과도한 복잡함) 감점을 뺀 최종 점수 |
| 정규화(L1/L2, Regularization) | 트리 잎의 개수·가중치 크기에 페널티를 줘 과적합을 억제 | 답안지를 너무 빽빽하게 쓰면 감점 |
| 2차 테일러 근사 | XGBoost가 목적함수를 1차(기울기)뿐 아니라 2차(곡률)까지 근사해 더 정확하고 빠르게 최적 분할을 찾는 수학적 기법 | 방향(1차)뿐 아니라 커브의 휘는 정도(2차)까지 보고 다음 걸음을 정함 |
| Level-wise(수평 성장) | 트리의 한 레벨(층) 전체를 균등하게 다 분할한 뒤 다음 레벨로 내려감(XGBoost 기본) | 건물을 한 층씩 골고루 다 올리고 다음 층으로 |
| Leaf-wise(수직 성장) | 현재 리프들 중 손실 감소가 가장 큰 리프 하나만 골라 분할(LightGBM 기본) | 가장 급한 곳부터 계속 파고드는 굴착 |
| Exact Greedy | 모든 데이터를 정렬해 가능한 모든 분할점을 다 검사하는 정확한 방식(느림) | 모든 경우의 수를 하나씩 다 확인 |
| 히스토그램 기반 분할 | 연속값을 미리 256개 안팎의 구간(bin)으로 나눠, 정렬 대신 구간 경계만 검사 | 자를 촘촘한 눈금 대신 굵은 눈금으로 바꿔 빠르게 재기 |
| GOSS(Gradient-based One-Side Sampling) | 그래디언트(오차)가 큰 샘플은 전부 쓰고, 작은 샘플은 일부만 무작위로 뽑아 계산량을 줄이는 LightGBM 샘플링 기법 | 틀린 문제는 다 보고, 맞은 문제는 몇 개만 훑어봄 |
| EFB(Exclusive Feature Bundling) | 동시에 0이 아닌 경우가 거의 없는 희소 특징들(예: 원-핫 인코딩된 카테고리)을 하나로 묶어 차원을 줄이는 LightGBM 기법 | 서로 겹칠 일 없는 스위치 여러 개를 다이얼 하나로 합침 |
| learning rate(eta, shrinkage) | 각 트리의 기여도를 줄여 한 번에 너무 크게 이동하지 않게 하는 계수 | 한 걸음씩 조심스럽게 나아가기 |

## 깊이 이해

### GBM의 연산 병목 — 수치로 이해
- 결정 트리는 각 분할 지점을 찾을 때 특징값 기준으로 데이터를 정렬해야 한다. N건, 특징 F개, 정렬 비용 O(N log N)이라면, 한 트리를 만드는 데 O(N log N × F)가 든다.
- N=1,000만 건이면 log₂(10,000,000)≈23. 특징이 100개면 한 트리당 대략 10,000,000 × 23 × 100 ≈ 2.3×10¹⁰번의 비교 연산이 필요하다. 부스팅은 트리를 수백 개(예: 500개) 순차로 쌓으므로 이 비용이 그대로 500배가 된다 — 기존 GBM이 대용량에서 비현실적이었던 이유다.

### XGBoost의 개선 — 2차 근사와 정규화
- XGBoost는 목적함수를 1차 미분(그래디언트)만 쓰던 기존 GBM과 달리, 2차 미분(헤시안)까지 테일러 전개로 근사해 뉴턴법처럼 더 정확한 방향으로 한 번에 수렴한다 — 같은 성능에 더 적은 트리 수로 도달한다.
- 목적함수에 L1/L2 정규화 항(트리 잎 개수·가중치 크기 페널티)을 명시적으로 추가해, 트리가 무한정 복잡해지는 것을 수식으로 억제한다. 이것이 기존 GBM과의 가장 큰 수학적 차이다.
- Exact Greedy(전수 탐색)와 히스토그램 근사 방식을 모두 지원하고, 특징 정렬을 블록 단위로 미리 캐싱해 병렬(멀티코어)로 처리한다.

### LightGBM의 개선 — 히스토그램·GOSS·EFB (수치로 이해)
- 히스토그램 기반 분할: 연속값을 256개 구간으로 미리 이산화(binning)하면, 분할점 탐색이 정렬 기반 O(N log N) 대신 구간 수만큼인 O(bins)≈O(255)로 줄어든다. N=1,000만 건 기준, 정렬 비교 약 2.3×10⁸회(특징당) 대비 히스토그램은 데이터를 한 번 스캔해 빈에 누적(O(N)=10⁷)한 뒤 255개 구간만 비교하면 되어 자릿수 단위로 빨라진다.
- GOSS: 예를 들어 그래디언트 상위 20%(a=0.2)는 전부 사용하고, 나머지 80% 중 10%(b=0.1)만 무작위 샘플링하면, 전체 데이터의 20%+8%=28%만으로 분할을 탐색하면서도 오차가 큰(학습이 덜 된) 샘플을 놓치지 않는다.
- EFB: 원-핫 인코딩된 카테고리 특징 10개가 있고 서로 동시에 1인 경우가 없다면, 이 10개를 값 구간을 겹치지 않게 오프셋을 줘 1개의 특징으로 병합한다 — 차원이 10배 줄어든다.
- 결과적으로 Leaf-wise 성장과 결합해, 1,000만 건 신용카드 사기 탐지 데이터에서 XGBoost가 2시간 걸린다면 LightGBM은 메모리 사용량을 절반 수준으로 줄이고 약 30분 만에 비슷한 정확도로 학습을 마친다.

### Level-wise vs Leaf-wise — 트리 모양으로 이해
- 리프 8개가 될 때까지 키운다고 하면, Level-wise(XGBoost)는 깊이 3에서 모든 리프가 균등하게 8개가 되도록 각 레벨을 다 분할한다 — 균형 잡힌 트리.
- Leaf-wise(LightGBM)는 손실 감소가 가장 큰 리프 하나만 골라 쪼개기를 반복하므로, 같은 리프 8개라도 어떤 가지는 깊이 6까지 뻗고 다른 가지는 깊이 2에 머무를 수 있다 — 비대칭 트리. 같은 리프 수라면 Leaf-wise가 손실을 더 많이 줄이지만, 데이터가 적으면(예: 1만 건 이하) 소수 샘플에 지나치게 맞춰 과적합하기 쉽다.

### 판별 원리 — 언제 무엇을 쓰나
- 데이터가 수백만 건 이상이고 학습 시간·메모리가 병목이면 LightGBM을 우선 검토한다.
- 데이터가 1만 건 이하로 적거나 과적합 위험 관리가 중요하면(Leaf-wise가 소수 샘플에 과도하게 맞출 수 있으므로) XGBoost나 Random Forest를 우선 검토한다.
- 결측치가 많은 정형 데이터는 두 알고리즘 모두 결측치를 자동 처리하는 분기 규칙을 학습하므로 별도 대체(imputation) 없이도 바로 쓸 수 있다.

## 연결 개념
- 앙상블 학습 (063) — 배깅·부스팅·스태킹 중 부스팅 계열의 구체적 구현체가 XGBoost·LightGBM
- Gradient Boosting Machine(GBM) — 두 알고리즘의 뼈대가 되는 원조 부스팅 알고리즘

## Ⅰ. 개요 및 필요성

- 정의: 결정 트리를 순차적으로 추가하며 잔차(Residual)를 줄여가는 그래디언트 부스팅 머신(GBM)의 고도화 구현체
- 배경: 기존 GBM 알고리즘은 분할 탐색 비용이 크고, 직렬 연산으로 인해 대용량 데이터 학습 시 타임아웃이 발생함
- 필요성: 정칙화(Regularization)를 통한 과적합 방지와 하드웨어 병렬 최적화를 통해 분류/회귀 태스크의 상용화 요건(속도, 정확도)을 충족해야 함

## Ⅱ. 구조 및 구성요소

```text
학습 데이터 -> 베이스 모델(트리 1) -> 오차(잔차) 계산 -> 트리를 순차 추가(학습) -> 앙상블 최종 예측
                                     +-> XGB: Level-wise 병렬 분할
                                     +-> LGBM: Leaf-wise + 히스토그램 분할
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 목적 함수 (Objective) | 학습 손실과 정칙화 항(L1, L2)의 합 | 과적합 방지 역할 수행 |
| 노드 분할(Split) | 정보 획득량(Information Gain) 최대화 지점 탐색 | Exact Greedy 또는 Histogram |
| 트랜잭션 병렬화 | 특징 정렬(Feature Sorting) 및 블록 단위 메모리 할당 | XGBoost의 속도 개선 코어 |
| EFB (Exclusive Feature Bundling) | 배타적 희소 특징을 단일 특징으로 병합 | LightGBM의 메모리 압축 |

> 요약: 모델은 목적 함수를 최소화하는 방향으로 트리를 추가하며, 분할 탐색과 메모리 병합 기법으로 성능을 극대화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
초기 예측값 설정 -> 기울기(Gradient) 도출 -> 히스토그램/정렬 기반 분할 노드 탐색 -> 트리 성장 -> 모델 업데이트
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 부스팅 초기화 및 Gradient 계산 | 잔차(Residual) 산출 |
| 2 | 분할 임계값 탐색 | 데이터 스캔 복잡도 $O(\#data \times \#feature)$ 감소 |
| 3 | 최적 노드 분할 적용 | XGB (Level-wise) / LGBM (Leaf-wise) 적용 |
| 4 | 리프 노드 가중치 업데이트 및 트리 추가 | Learning rate(eta) 반영 |

> 요약: 현재 모델의 예측 오차를 미분하여 기울기를 구하고, 이 오차를 줄이도록 트리 구조를 최적화하여 갱신한다.

---

## Ⅳ. 특징

| 구분 | XGBoost (eXtreme Gradient Boosting) | LightGBM |
|:---|:---|:---|
| 성장 방식 | Level-wise (균형 우선 성장) | Leaf-wise (손실 최대 리프 우선 분할) |
| 노드 분할 탐색 | Exact Greedy 또는 히스토그램 근사 | 히스토그램 기반 특화 |
| 데이터 제약 | 소규모 데이터에서도 과적합에 강함 | 1만 건 이하 데이터 학습 시 과적합 취약 |

> 요약: XGBoost는 안정적인 균형 구조로 정확도를 담보하고, LightGBM은 비대칭 성장을 통해 연산 시간을 압축한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 Random Forest | XGBoost | LightGBM |
|:---|:---|:---|:---|
| 학습 방식 | 배깅 (독립적 다수결) | 부스팅 (순차적 오차 보완) | 부스팅 + 히스토그램 + GOSS |
| 주요 강점 | 병렬 처리 용이, 하이퍼파라미터 둔감 | 강력한 성능, 결측치 자동 대처 | 압도적 속도, 메모리 사용량 최소화 |
| 선택 기준 | 베이스라인 모델 구축 | 10만 건 미만 정형 데이터 정밀 분류 | 수백만 건 이상 대용량 추천/탐지 |

> 요약: 데이터 규모가 작으면 Random Forest/XGBoost를, 대용량 상용 트래픽에는 LightGBM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과적합(Overfitting) | Leaf-wise 성장에 따른 과도한 깊이 (LGBM) | `max_depth`, `num_leaves` 파라미터 제한 통제 | Train/Test AUC 격차 |
| 리소스 부족 | One-hot 인코딩에 의한 희소 특징 차원 폭발 | LGBM 내장 카테고리 피처 처리 활성화 (EFB) | 학습 시 Peak RAM |
| 불균형 데이터 편향 | 사기 탐지 등에서 소수 클래스 예측 실패 | `scale_pos_weight` 조정, Focal Loss 적용 | F1-score, Recall |

> 요약: 트리 깊이 제한과 내장 카테고리 최적화를 통해 과적합과 차원 폭발 리스크를 제어한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 분류 정확도 | ROC-AUC 0.85 이상, F1 0.80 이상 | 교차 검증 (K-Fold), 혼동 행렬 |
| 학습 효율성 | 100만 건 데이터 기준 10분 이내 학습 완료 | Time 모니터링, 프로파일링 |
| 추론 지연시간 | 단건 예측 지연 p95 10ms 이하 | 추론 서버 API 벤치마크 테스트 |

> 요약: 대규모 부스팅 모델 도입 시에는 ROC-AUC 지표 외에 메모리 피크와 추론 지연시간을 반드시 통제해야 전체 파이프라인이 최적화된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 금융 사기 탐지(FDS): XGBoost를 적용하여 결측치가 많은 금융 트랜잭션 데이터를 전처리 없이 학습하고, 1만 건 미만의 소수 이상 거래 탐지율(Recall)을 90% 이상 확보한다.
2. 커머스 클릭 예측(CTR): 1,000만 건 이상의 일일 로그 데이터 학습 속도 병목을 해결하기 위해, LightGBM을 도입하고 `categorical_feature` 내장 옵션을 통해 학습 메모리를 50% 절감한다.
3. 파라미터 자동 최적화: Optuna 또는 Hyperopt를 MLOps 파이프라인에 통합하여, XGBoost의 `eta`와 `max_depth`, LightGBM의 `num_leaves`를 베이지안 최적화 기반으로 자동 튜닝한다.

**결론 (2줄):**
- 기술사 판단: 정형 데이터(Tabular Data)의 분류/회귀 문제에서는 딥러닝보다 트리 기반 부스팅(XGBoost, LightGBM)이 학습 효율과 해석력(Feature Importance) 측면에서 최우선 도입 대상이다.
- 향후 방향: 최근에는 GPU 가속 지원(cuML)과 XGBoost/LightGBM을 통합하여 활용하는 앙상블 스태킹(Stacking) 방식이 상용 시스템의 표준 베이스라인으로 자리 잡고 있다.
