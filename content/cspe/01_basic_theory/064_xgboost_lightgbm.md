# 📖 【암기용】 개념 완전 이해

> 목적: XGBoost·LightGBM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: XGBoost와 LightGBM은 그래디언트 부스팅 트리 계열 모델이다.
- **왜 필요한가**: 기업 데이터는 표 형태, 결측치, 범주형 변수, 비선형 관계가 섞여 있다. 부스팅 트리는 전처리 부담을 줄이면서 예측 오류를 단계적으로 보정한다.
- **핵심 직관**: 첫 나무가 틀린 부분을 다음 나무가 집중 보정하고, 이를 여러 번 반복해 손실 함수를 줄이는 방식이다.

## 깊이 이해
- **배경·문제의식**: 선형 모델은 변수 간 비선형 상호작용을 놓칠 수 있고, 단일 의사결정나무는 분산이 크다. Gradient Boosting Decision Tree(GBDT)는 약한 트리를 순차적으로 더해 손실 함수의 음의 그래디언트를 학습한다.
- **작동 원리**: XGBoost는 2차 미분 기반 목적함수, 정규화, 병렬 처리를 제공한다. LightGBM은 histogram 기반 분할, leaf-wise 성장, GOSS, EFB로 대규모 탭ular 데이터 처리 비용을 줄인다.
- **비유**: 시험 오답노트를 볼 때 많이 틀린 유형을 다음 학습에서 더 많이 풀고, 반복마다 점수를 조금씩 보정하는 것과 같다.
- **구체 예시**: 신용평가 100만 행, 변수 300개에서 LightGBM은 histogram bin 255개를 사용해 연속값 분할 후보를 압축하고, early stopping 100라운드로 과적합을 제어한다.
- **흔한 오해·주의점**: LightGBM의 leaf-wise 성장은 손실 감소가 큰 잎을 깊게 확장하므로 max_depth, num_leaves, min_data_in_leaf를 제한하지 않으면 검증 성능이 하락한다.

## 연결 개념
- 그래디언트 부스팅: 손실 함수의 그래디언트를 순차 보정
- 앙상블 학습: 여러 약한 학습기의 결합
- 피처 중요도·SHAP: 트리 모델 해석 도구

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: XGBoost·LightGBM은 약한 의사결정나무를 순차 결합해 손실을 줄이는 GBDT 구현체이다.
> 2. **가치**: 탭ular 데이터에서 결측·비선형·상호작용을 처리하고 AUC·RMSE 기준 모델을 제공한다.
> 3. **판단 포인트**: 데이터 크기, 범주형 변수, 학습시간, 과적합 통제 파라미터로 XGBoost와 LightGBM을 선택한다.

---

## Ⅰ. 개요 및 필요성

XGBoost·LightGBM은 부스팅 트리 모델이다. 금융·제조·추천의 표 데이터는 비선형성과 변수 상호작용이 강해 선형 모델만으로 오류가 남는다. GBDT 계열은 잔차를 순차 보정하고 정규화·조기중단으로 일반화 성능을 통제한다.

---

## Ⅱ. 구조 및 구성요소

```text
탭ular 데이터 -> 트리 분할 후보 -> 약한 트리 학습 -> 손실 보정 -> 예측 합산
                            +-> 정규화/조기중단 -> 과적합 통제
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 약한 트리 | 손실의 잔차 또는 그래디언트 학습 | depth 3~8 기준 |
| 목적함수 | 분류·회귀 손실 최적화 | logloss, RMSE, MAE |
| 정규화 | 트리 복잡도와 가중치 제한 | lambda, alpha, min_child_weight |
| 가속 기법 | 분할 후보와 특징 수 축소 | histogram, GOSS, EFB |

> 요약: XGBoost·LightGBM은 약한 트리, 목적함수, 정규화, 가속 기법으로 손실을 순차 보정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 전처리 -> 초기 예측 -> 그래디언트 계산 -> 트리 추가 -> 조기중단/평가
                +-> 검증셋 모니터링 -> 최적 라운드 선택
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 결측·범주형·학습/검증 분리 | leakage 0건, stratified split |
| 2 | 손실 함수와 평가지표 선택 | AUC, logloss, RMSE |
| 3 | 트리 반복 학습과 learning_rate 적용 | n_estimators, early stopping |
| 4 | 튜닝·해석·배포 판단 | SHAP, p95 추론, drift |

> 요약: 부스팅 트리는 검증셋 손실을 감시하며 트리를 추가하고, 조기중단 지점의 모델을 최종 선택한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 탭ular 비선형 관계와 결측 처리 | AUC 0.90 이상 기준 모델 |
| 한계 | 파라미터 민감도와 해석 부담 | depth, num_leaves, learning_rate |
| 비교 대상 | 랜덤포레스트, 딥러닝 | 표 데이터 100만 행 이하 우선 |
| 수치 기준 | learning_rate 0.01~0.1, early stopping 50~100 | 검증 손실 정체 라운드 |

> 요약: XGBoost·LightGBM은 탭ular 데이터 기준 모델이나 과적합과 파라미터 민감도를 검증셋으로 통제해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 랜덤포레스트는 병렬 독립 트리 | GBDT는 순차 잔차 보정 | 오류 보정 필요 시 GBDT |
| 비용/성능 | XGBoost는 정규화·안정적 학습 | LightGBM은 histogram·leaf-wise | 100만 행 이상은 LightGBM 검토 |
| 운영/위험 | 딥러닝은 특징학습 강점 | GBDT는 탭ular 해석·배포 용이 | SHAP 설명 요구 |

> 요약: 탭ular 데이터에서는 GBDT를 우선 검토하고, 데이터 규모와 학습시간에 따라 XGBoost와 LightGBM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과적합 | depth·num_leaves 과대 | max_depth 제한, early stopping | train-test AUC 차이 3%p 이하 |
| 데이터 누수 | 사후 변수 포함 | 시점 기준 피처 컷오프 | leakage 점검 0건 |
| 운영 편향 | 데이터 분포 변화 | PSI·KS 모니터링, 재학습 | PSI 0.2 이하 |

> 요약: GBDT 운영은 과적합, 데이터 누수, 분포 변화를 튜닝 규칙과 모니터링 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 예측 품질 | AUC 0.90 이상, logloss 기준선 대비 5% 감소 | holdout, 5-fold CV |
| 처리 비용 | 학습 1시간 이하, 추론 p95 50ms 이하 | 학습 로그, API 벤치마크 |
| 해석·감사 | 상위 SHAP 변수 20개 검토 | SHAP summary, 피처 문서 |

> 요약: XGBoost·LightGBM은 예측 품질, 처리 비용, SHAP 기반 설명성을 함께 점검해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 기준선은 Logistic Regression과 Random Forest로 설정하고, GBDT 채택 기준을 AUC 2%p 이상 개선으로 둠
2. LightGBM은 num_leaves 31~255, min_data_in_leaf 20~100, early stopping 100라운드로 과적합 통제함
3. 배포 후 PSI 0.2 초과 또는 AUC 3%p 하락 시 재학습하며 SHAP 상위 변수 변동을 월 1회 점검함

**결론 (2줄):**
- 기술사 판단: 탭ular·비선형·중대형 데이터는 GBDT, 이미지·텍스트 원천 데이터는 딥러닝을 우선 선택함
- 향후 방향: XGBoost·LightGBM은 AutoML, Feature Store, 모델 모니터링과 결합해 기업 예측 플랫폼의 표준 모델로 활용됨
