## Ⅰ. 개요
- **정의**: 정규 언어를 기술하는 대수적 표기법으로, 문자열 패턴을 선택·연결·반복으로 정의함
- **배경/필요성**: 유한 오토마톤(022 참조)의 상태 다이어그램 대신 간결한 텍스트로 패턴을 명세할 수단이 필요함
- **비유**: 레시피 재료란에 "밀가루 또는 쌀가루, 설탕 1회 이상"처럼 허용 조합을 기술하는 규칙과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규 표현식과 유한 오토마톤의 등가성 이해 여부 | 3대 연산(합집합·연결·클리니 폐포)과 NFA 변환 | 역참조 등 확장 문법은 정규 언어 범위를 초과함을 구분할 것 |

> 요약: 선택·연결·반복 연산으로 정규 언어를 간결하게 기술하는 패턴 표기법임

## Ⅱ. 구성요소
```text
  정규 표현식: (a|b)*abb

  분해:
  (a|b)  -->  선택(합집합)
    *    -->  클리니 폐포(0회 이상 반복)
   abb   -->  연결(순차 결합)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 합집합(`\|`) | 두 패턴 중 하나를 선택함 | 메뉴에서 A 또는 B 중 택 1 |
| 연결(concatenation) | 두 패턴을 순서대로 이어 붙임 | 단어를 글자 순서대로 나열하는 것 |
| 클리니 폐포(`*`) | 패턴을 0회 이상 반복함 | "원하는 만큼 리필 가능"과 같은 무제한 반복 |
| 기본 기호 | 알파벳 문자 1개 또는 공문자열(`epsilon`)을 나타냄 | 레고 블록 1개에 해당하는 최소 단위 |

> 요약: 합집합·연결·클리니 폐포와 기본 기호로 모든 정규 언어를 표현함

## Ⅲ. 절차
```text
  1.패턴작성       2.NFA변환        3.DFA변환        4.패턴매칭
  (정규식정의)     (Thompson구성)   (부분집합구성)   (입력문자열검사)
   |               |               |               |
   +---정규식------>+---NFA--------->+---DFA--------->+
  연산자조합       epsilon전이포함  결정적전이표     수리/거부판정
```
- 1단계: 합집합·연결·클리니 폐포를 조합하여 목표 패턴의 정규 표현식을 작성함
- 2단계: Thompson 구성법으로 정규 표현식을 epsilon-NFA로 변환함 (022 참조)
- 3단계: 부분집합 구성법으로 NFA를 DFA로 변환하여 결정적 전이 테이블을 생성함
- 4단계: DFA가 입력 문자열을 순차 처리하여 수리 상태 도달 여부로 매칭을 판정함

> 요약: 패턴 작성 → NFA 변환 → DFA 변환 → 매칭 실행의 4단계로 정규식을 처리함

## Ⅳ. 문제점
- DFA 상태 폭발: 복잡한 정규식의 DFA 변환 시 상태 수가 지수적으로 증가할 수 있음
- 표현력 제한: 중첩 괄호·교차 의존성 등 문맥 자유 이상의 패턴은 정규식으로 기술 불가함
- 역참조 비용: 실용 정규식 엔진의 역참조(`\1`) 기능은 NP-완전 문제를 유발하여 입력에 따라 처리 시간이 급증함

> 요약: 상태 폭발·표현력 제한·역참조 비용이 정규식 활용의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 지연(lazy) DFA 구성으로 실제 도달 상태만 생성하여 메모리 사용을 억제함
2. 중기: 문맥 자유 문법(024 참조)이나 PEG로 전환하여 정규식 범위 밖 패턴을 처리함
3. 장기: 역참조가 불필요한 패턴은 순수 DFA 엔진으로 분리 실행하여 최악 시간 복잡도를 $O(n)$으로 보장함

> 요약: 지연 DFA → 문법 확장 → 엔진 분리로 정규식의 한계를 보완함

## Ⅵ. 전망
- 발전 방향: 네트워크 IDS·로그 분석에서 FPGA 기반 정규식 하드웨어 매칭이 확대되는 추세임
- 기술사적 판단: 텍스트 처리·컴파일러 어휘 분석의 핵심 도구로서 지속 활용됨
- 기술사 제언: 순수 정규식과 확장 문법의 계산 복잡도 차이를 인지하고 용도에 맞는 엔진을 선택해야 함
