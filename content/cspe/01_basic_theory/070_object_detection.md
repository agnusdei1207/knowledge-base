## 미리 알고가기

- 바운딩 박스($Bounding$ $Box$): 이미지 상에서 검출된 객체의 영역을 나타내는 4개의 좌표($x, y, w, h$)로 구성된 직사각형임
- $IoU$($Intersection$ $over$ $Union$): 두 영역의 합집합 면적 대비 교집합 면적의 비율로, 예측한 위치가 실제 위치와 얼마나 일치하는지 평가함
- $NMS$($Non-Maximum$ $Suppression$): 동일한 객체 주위에 겹쳐서 생성된 수많은 예측 박스들 중 신뢰도가 가장 높은 박스만 남기고 나머지를 제거하는 후처리임
- 앵커 박스($Anchor$ $Box$): 다양한 크기와 비율의 후보 사각형들을 미리 정의해 두고, 모델이 이 박스를 미세 조정하여 실제 위치를 찾도록 돕는 기준선임

## Ⅰ. 개요

- **정의/개념**: 객체 탐지(Object Detection)는 이미지 또는 비디오 안에서 관심 대상이 되는 사물들의 위치(Localization)를 바운딩 박스로 표시하고, 각 사물의 카테고리(Classification)를 동시에 식별해내는 컴퓨터 비전의 핵심 분야임
- **배경/필요성**: 단순히 이미지 전체의 대표 카테고리를 맞추는 '이미지 분류'만으로는 자율주행차의 장애물 회피, CCTV의 침입 감지, 스마트 팩토리의 결함 스캔 등 구체적인 사물의 위치가 필수적인 산업 현장의 요구를 충족할 수 없기 때문에 설계됨

## Ⅱ. 특징

- 위치 검출($Localization$)과 분류($Classification$)를 동시에 완수해야 하므로 모델의 구조가 복잡하며, 한 이미지에 수십~수백 개의 사물이 밀집해 있는 다중 타깃 상황을 효과적으로 처리해야 함
- 2단계로 나누어 영역 제안 후 분류하는 $2-Stage$ 방식(R-CNN 계열)과, 단번에 경계선과 클래스를 구하는 $1-Stage$ 방식(YOLO 계열)의 두 갈래로 나뉘어 진화함
- 최근 모델들은 성능 평가 시 오탐율과 미탐율을 동시에 반영하는 '평균 정밀도($mAP$)' 지표와 실시간 처리 속도인 '$FPS$'를 최우선 기준으로 두고 최적화를 진행함

## Ⅲ. 종류 및 비교

| 판단 기준 | 2-Stage Detector (R-CNN 계열) | 1-Stage Detector (YOLO 계열) |
|:---|:---|:---|
| **처리 방식** | 후보 영역 추출($RPN$)과 분류를 단계별로 수행 | 이미지 전체를 그리드로 나누어 한번에 동시 처리 |
| **추론 속도** | 상대적으로 느림 (실시간 적용 어려움) | 극도로 빠름 (CCTV, 모바일 장치 실시간 대응) |
| **탐지 정확도** | 상대적으로 높음 (정밀 분류 및 작은 박스 강점) | 중간 (작은 객체가 오밀조밀 모인 상황에 취약) |
| **대표 알고리즘** | $Fast$ $R-CNN$, $Faster$ $R-CNN$ | $YOLO$ $v1 \sim v8$, $SSD$ |

> 요약: R-CNN은 속도를 희생하고 '정밀함'을, YOLO는 약간의 정밀함을 양보하고 '실시간 속도'를 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 백본 ($Backbone$) | 입력 이미지에서 윤곽선, 텍스트 등 시각 특징 벡터를 추출하는 역할(ResNet 등)임 |
| 넥 ($Neck$) | 백본에서 추출한 크고 작은 해상도의 특징 맵들을 서로 융합($FPN$ 등)하여 다각도로 정보량을 높임 |
| 헤드 ($Head$) | 최종적으로 바운딩 박스의 미세 조정 오차와 클래스별 확률을 도출하는 판정 층임 |
| $NMS$ 알고리즘 | 한 사물에 중복으로 쳐진 경계선들을 신뢰도와 $IoU$ 임계값을 기준으로 걸러내는 최종 정화 장치임 |

```text
[ 1-Stage vs 2-Stage 흐름 비교 ]
- 2-Stage: Input -> Backbone -> [Region Proposals] -> [Crop & Classify] -> Output
- 1-Stage: Input -> Backbone -> [Grid Regress & Classify (Single Pass)] -> Output
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 이미지 입력  | --> | 특징 추출/융합| --> | 위치/클래스예측| --> | NMS 중복제거 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **특징 맵 생성** — 입력 이미지를 합성곱 인프라(백본)에 통과시켜 각 공간적 위치에 해당하는 고밀도 특징 데이터들을 얻음
2. **다중 해상도 결합** — 넥 단계의 특성 피라미드($FPN$)를 거치며, 넓은 시야의 정보와 세밀한 해상도의 지도를 결합하여 작고 섬세한 객체를 식별할 준비를 마침
3. **병렬 예측 수행** — 헤드 단에서 각 특징 위치마다 사전에 정의된 앵커 박스들의 변위($\Delta x, \Delta y, \Delta w, \Delta h$)와 각 클래스일 확률을 한꺼번에 구함
4. **후처리 정밀화** — 탐지 신뢰도가 낮은 박스들은 1차 여과하고, 동일 사물에 대해 $IoU$가 높게 겹쳐서 출현한 잉여 박스들을 $NMS$로 깔끔하게 정리하여 최종 결과를 화면에 뿌려줌

## Ⅵ. 실무 적용 및 유의점

1. 크기가 매우 작거나(예: 멀리 있는 차량) 서로 겹쳐서 가려진 사물을 탐지할 때는 모델이 인지하지 못하고 놓치는 병목 현상이 발생하므로, 특징 피라미드 네트워크($FPN$)를 조밀하게 강화하거나 고해상도 이미지를 조각내어 순차 처리하는 크롭($Crop$) 추론을 고려해야 함
2. 자율주행 센서나 소형 카메라 엣지($Edge$) 디바이스에 탑재할 때는 제한된 메모리와 전력 문제로 거대 모델을 돌릴 수 없으므로, $TensorRT$ 같은 가속화 도구를 사용하여 모델을 8비트 정수형($INT8$)으로 '양자화' 처리하거나 모델을 슬림하게 깎는 '지식 증류'가 권장됨

## Ⅶ. 결론

- 객체 탐지는 공간과 의미를 결합하여 기계가 주변 환경을 입체적으로 목격하게 만드는 컴퓨터 비전의 중심축이며, 설계자는 실시간 지연시간 요구 수준과 작은 객체 탐지율을 정밀하게 분석하여 비즈니스 환경에 가장 안정적인 모델 파이프라인을 구축해야 함
