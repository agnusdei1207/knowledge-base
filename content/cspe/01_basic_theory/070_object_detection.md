## 미리 알고가기

- Bounding Box: 이미지 안 객체 위치를 좌표 사각형으로 나타낸 결과임
- Localization: 객체가 이미지의 어느 위치에 있는지 찾는 작업임
- Classification: 찾은 객체가 어떤 클래스인지 판별하는 작업임
- IoU: 예측 박스와 정답 박스가 겹치는 비율로 위치 정확도를 평가함
- NMS: 겹치는 후보 박스 중 신뢰도가 높은 것만 남기는 후처리임
- mAP: 여러 클래스와 IoU 기준에서 평균 정밀도를 측정하는 탐지 성능 지표임

## Ⅰ. 개요

- **정의**: 객체 탐지는 이미지나 영상에서 여러 객체의 위치 좌표와 클래스 레이블을 동시에 예측하는 컴퓨터 비전 기술임. 박스 위치 정확도와 분류 신뢰도를 기준으로 자율주행, 감시, 제조 검사처럼 `무엇이 어디에 있는지`가 필요한 업무에 사용함
- **배경/필요성**: 이미지 분류는 한 장면의 대표 클래스만 알려주지만 실제 서비스는 객체 수, 위치, 크기, 겹침 상태까지 알아야 제어와 의사결정이 가능함
- **비유**: 사진 속 모든 대상에 이름표와 사각형 테두리를 동시에 붙이는 작업과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐지와 분류 차이 설명 | 클래스와 위치를 동시에 출력 | 이미지 분류와 동일하게 서술 |
| 1-stage와 2-stage 비교 | YOLO 계열, Faster R-CNN 계열 | 속도-정확도 트레이드오프 누락 |

> 요약: 객체 탐지는 이미지 안의 객체 종류와 위치를 함께 예측해 후속 제어·검색·분석이 가능하게 하는 비전 기술임

## Ⅱ. 특징/비교

| 판단 기준 | 2-Stage 탐지 | 1-Stage 탐지 | Transformer 탐지 |
|:---|:---|:---|:---|
| 처리 방식 | 후보 영역을 만든 뒤 분류·회귀함 | 한 번의 네트워크 통과로 박스와 클래스를 예측함 | 객체 query와 attention으로 직접 예측함 |
| 강점 | 정확도와 소형 객체 처리에 강함 | 실시간 처리와 엣지 배포에 유리함 | 전역 문맥과 중복 제거 단순화에 유리함 |
| 약점 | 구조가 복잡하고 추론이 느림 | 겹침·소형 객체에서 오탐이 늘 수 있음 | 학습 데이터와 계산 자원이 많이 필요함 |
| 선택 기준 | 정확도 우선 검사·의료 | 실시간 영상·자율주행 | 복잡 장면의 전역 관계 탐지 |

> 요약: 객체 탐지 모델은 정확도, 지연 시간, 장면 복잡도, 배포 환경을 기준으로 계열을 선택함

- **평가 기준**: mAP만이 아니라 FPS, 오탐률, 미탐률, 소비 전력, 후처리 비용을 함께 확인함
- **데이터 기준**: 박스 라벨 품질과 클래스 불균형이 모델 성능에 직접 영향을 줌
- **운영 기준**: 조명, 날씨, 카메라 각도 변화가 학습 데이터와 다르면 성능이 크게 흔들릴 수 있음

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| Input Image | ---> | Backbone    | ---> | Neck / FPN  |
| frame       |      | features    |      | multi-scale |
+------+------+      +------+------+      +------+------+
       |                    |                    |
       v                    v                    v
+-------------+      +-------------+      +-------------+
| Detection   | <--- | NMS / Post  | <--- | Head        |
| Results     |      | Processing  |      | box + class |
+-------------+      +-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 영상 | 탐지 대상 이미지 또는 프레임이며 해상도와 품질이 성능에 영향을 줌 | 관찰 장면 |
| Backbone | CNN 또는 ViT로 저수준·고수준 시각 특징을 추출함 | 시각 피질 |
| Neck/FPN | 여러 해상도의 특징을 결합해 크기가 다른 객체를 찾게 함 | 다초점 렌즈 |
| Detection Head | 박스 좌표, 객체성 점수, 클래스 확률을 예측함 | 판정관 |
| 후처리 | NMS, confidence threshold로 중복과 낮은 신뢰도 후보를 제거함 | 정리 담당 |

> 요약: 객체 탐지는 특징 추출, 다중 스케일 융합, 박스·클래스 예측, 후처리를 거쳐 최종 탐지 결과를 산출함

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Preprocess| --> | Extract   | --> | Predict   | --> | Filter    |
| Image     |     | Features  |     | Box/Class |     | by NMS    |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
resize/norm        feature maps       candidates       final boxes
```

1. **영상 전처리**: 입력 이미지를 모델 해상도로 resize하고 정규화하며 배치 입력 형태로 변환함
2. **특징 추출**: backbone과 FPN이 다양한 크기의 객체를 표현하는 feature map을 생성함
3. **후보 예측**: detection head가 후보 박스의 좌표, confidence, 클래스 확률을 계산함
4. **후처리·평가**: confidence threshold와 NMS로 중복을 제거하고 IoU, mAP, FPS로 결과를 평가함

> 요약: 객체 탐지는 전처리된 영상에서 다중 스케일 특징을 만들고 박스 후보를 예측한 뒤 중복 제거로 최종 결과를 확정함

## Ⅴ. 문제점

- **P1 속도-정확도 충돌**: 정확도 높은 모델은 구조가 복잡해 지연이 크고, 실시간 모델은 소형·겹침 객체 정확도가 낮아질 수 있음
- **P2 라벨 비용과 불균형**: 박스 라벨링은 비용이 크며 희귀 클래스의 데이터 부족이 미탐으로 이어짐
- **P3 도메인 이동 취약성**: 학습 환경과 다른 조명, 날씨, 카메라 각도에서는 오탐과 미탐이 증가함

> 요약: 객체 탐지의 핵심 제약은 실시간성, 박스 라벨 품질, 운영 환경 변화에 대한 견고성임

## Ⅵ. 개선방안

- **P1 대응**: 경량 backbone, anchor-free head, 모델 양자화, TensorRT 최적화를 적용함 (확인: mAP-FPS 파레토)
- **P2 대응**: active learning, 합성 데이터, 클래스 가중치, focal loss로 라벨 비용과 불균형을 완화함 (확인: rare class AP)
- **P3 대응**: 도메인 증강, 야간·우천 데이터 보강, test-time adaptation을 적용함 (확인: cross-domain mAP 하락률)

> 요약: 모델 경량화, 데이터 수집 전략, 도메인 적응을 함께 설계해야 탐지 모델을 운영 환경에 맞출 수 있음

## Ⅶ. 전망

- **발전 방향**: 객체 탐지는 엣지 AI, 멀티모달 센서, 3D 탐지, 추적 모델과 결합해 실시간 공간 인식으로 확장될 전망임
- **설계 관점**: mAP 목표, FPS, 객체 크기, 라벨 비용, 배포 장비를 기준으로 1-stage, 2-stage, anchor-free 구조를 선택해야 함
- **검증 관점**: mAP-FPS 파레토, rare class AP, cross-domain mAP 하락률, 오탐·미탐 비용을 함께 측정해야 모델 실효성을 판단할 수 있음
- **운영 관점**: 카메라 각도, 조명, 날씨, 센서 교체에 따른 drift를 감시하고 라벨 보강과 모델 재학습 절차를 운영해야 함
- **적용 관점**: 제조 검사, 교통, 보안 관제처럼 위치와 클래스가 동시에 필요한 업무에 적합하며 단순 전체 판정은 이미지 분류로 충분할 수 있음
- **보안·신뢰 관점**: 스티커, 패턴, 조명 교란 같은 공격 입력이 오탐·미탐을 유발할 수 있으므로 강건성 테스트와 임계값 정책이 필요함
- **기술사 제언**: 답안에서는 탐지 출력이 `클래스 + 위치`라는 점과 속도-정확도-라벨 비용의 선택 기준을 명확히 써야 함
