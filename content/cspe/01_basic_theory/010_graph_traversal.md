## 미리 알고가기

- **정점($V$)과 간선($E$)**: 데이터를 담는 객체($Vertex$)와 그들 사이의 관계($Edge$)를 나타내는 그래프의 기본 구성 단위임
- **인접 리스트($Adjacency$ $List$)**: 각 정점에 연결된 이웃 정점들을 리스트로 관리하여 메모리 효율을 최적화한 표현 방식임
- **방문 배열($Visited$ $Array$)**: 이미 방문한 정점을 기록하여 무한 루프($Cycle$)와 중복 연산을 방지하는 장치임

## Ⅰ. 개요

- **통합 정의**: 시작 정점으로부터 간선을 따라 모든 정점을 빠짐없이 방문하는 과정이며, 방문 순서와 활용 자료구조에 따라 너비 우선($BFS$)과 깊이 우선($DFS$)으로 분류됨
- **개별 정의**:
  - **너비 우선 탐색 ($BFS$)**: 인접한 정점들을 우선적으로 모두 방문하며 층별($Level$)로 확산하는 방식임
  - **깊이 우선 탐색 ($DFS$)**: 한 경로를 따라갈 수 있을 때까지 깊게 탐색한 후 더 이상 갈 곳이 없으면 복귀($Backtracking$)하는 방식임
- **배경/필요성**: 복잡하게 얽힌 관계형 데이터(소셜 네트워크, 네트워크 토폴로지)에서 최단 거리 도출, 사이클 탐지, 연결 컴포넌트 식별 등 고차원 문제 해결의 기초 알고리즘으로 활용됨

## Ⅱ. 특징 및 비교

$BFS$와 $DFS$는 후보 정점을 관리하는 자료구조($Queue$ vs $Stack$)의 차이로 인해 탐색 방향과 활용 목적이 상이함.

| 비교 항목 | 너비 우선 탐색 ($BFS$) | 깊이 우선 탐색 ($DFS$) |
|:---|:---|:---|
| **관리 자료구조** | **큐 ($Queue$)** 기반 반복문 | **스택 ($Stack$)** 또는 **재귀** |
| **탐색 방향** | 수평적 확산 (층별 탐색) | 수직적 하강 (심도 탐색) |
| **최단 경로** | **가중치 없는 그래프에서 보장** | 최단 경로 보장 불가 |
| **시간 복잡도** | $O(V+E)$ (인접 리스트 기준) | $O(V+E)$ (인접 리스트 기준) |
| **PPA 관점** | 메모리 소모 큼 ($Queue$ 크기) | $CPU$ $Stack$ 부하 ($Recursion$) |
| **주요 용도** | 최단 경로, $Level$ 순회, $MST$ | 사이클 탐지, 위상 정렬, 백트래킹 |

> 요약: 거리($Hop$) 중심의 문제 해결에는 $BFS$를, 관계의 성질(순환 등) 분석에는 $DFS$를 선택하는 것이 효율적임.

## Ⅲ. 구성요소 및 탐색 구조

### 가. 분석 구성요소 (Architecture Insight)

| 구성요소 | 역할 및 정의 | 핵심 포인트 |
|:---|:---|:---|
| **$Frontier$** | 다음에 방문할 예정인 정점 집합 | 자료구조에 따라 탐색 전략 결정 |
| **$Visited$ $Map$** | 정점의 방문 상태 기록 ($Boolean$) | 중복 방문 및 사이클 방어 기제 |
| **$Adjacency$ $Info$** | 정점 간 연결 관계 데이터 | $O(V+E)$ 성능 보장용 자료구조 선택 |
| **$Backtrack$ $Point$** | 더 이상 갈 곳이 없을 때 되돌아갈 지점 | $DFS$의 논리적 연속성 유지 |

### 나. 탐색 원리 및 절차

```text
[BFS: 너비 우선]                    [DFS: 깊이 우선]
1. 시작 정점 Queue 삽입, 방문 표시    1. 시작 정점 방문 표시 및 재귀 호출
2. Queue에서 하나 꺼내(u) 처리       2. u의 인접 정점 중 미방문(v) 탐색
3. u의 미방문 인접 노드 모두 삽입     3. 즉시 v로 이동하여 1번 반복 (깊게)
4. Queue가 빌 때까지 반복            4. 더 없으면 복귀 (Backtrack)
```

## Ⅳ. Real-world Troubleshooting

1. **$DFS$의 재귀 한계 및 $Stack$ $Overflow$**
   - **문제**: 그래프 깊이가 깊을 경우 시스템 기본 재귀 한도를 초과하여 프로세스 비정상 종료
   - **대응**: 재귀 호출 대신 명시적 스택 자료구조를 사용하는 **반복문 기반 $DFS$**로 전환하여 메모리 제어권을 확보함

2. **$BFS$의 메모리 폭발 현상**
   - **문제**: 정점의 차수($Degree$)가 매우 큰 그래프(예: $Hub$ $Node$) 탐색 시 큐에 쌓이는 노드가 급증하여 $OOM$ 발생
   - **대응**: 탐색 깊이를 제한하는 **$IDDFS$** 또는 필요한 구간만 탐색하는 **양방향 탐색($Bidirectional$ $Search$)**을 고려함

3. **중복 방문 통제 시점 오류**
   - **문제**: 방문 처리를 큐에서 꺼낼 때($Pop$) 수행하여 동일 노드가 중복 삽입되는 비효율 발생
   - **대응**: 노드를 **큐에 넣는 시점($Push$)**에 즉시 방문 처리하도록 로직을 설계하여 연산 중복을 차단함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **네트워크 라우팅** | $BFS$ 기반 최단 홉($Hop$) 수 산출 | 경로 도달 지연, 데이터 전송 비용 |
| **정적 분석 도구** | $DFS$ 기반 순환 참조($Circular$ $Ref$) 탐지 | 빌드 오류 방지, 사이클 존재 여부 |
| **웹 크롤러** | 도메인 내 층별 수집($BFS$) vs 심층 수집($DFS$) | 페이지 수집량, 도메인 점유율 |
| **$GIS$ / 게임** | 격자 맵 미로 찾기 및 영역 채우기 ($Flood$ $Fill$) | 탐색 속도, 메모리 피크 점유량 |

## Ⅵ. 결론

그래프 탐색은 비정형 관계형 데이터를 가치 있는 정보로 변환하는 가장 핵심적인 알고리즘적 도구임. 기술사는 $BFS$와 $DFS$가 동일한 $O(V+E)$ 복잡도를 가짐에도 불구하고, $Queue$와 $Stack$이라는 자료구조의 특성이 가져오는 탐색 전략의 본질적 차이를 명확히 이해해야 함.

특히 현대의 대규모 그래프 처리 시스템(예: $Neo4j, Spark$ $GraphX$)에서는 단순 탐색을 넘어 병렬 처리와 분산 탐색 최적화가 필수적임. 따라서 알고리즘의 동작 원리를 넘어, 실제 운영 환경의 메모리 제약과 최악의 데이터 구조($Skewed$ $Graph$)에 유연하게 대응할 수 있는 아키텍처적 안목을 갖추어야 함.
