# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 그래프 탐색은 정점(Vertex)과 간선(Edge)으로 이루어진 그래프의 모든 정점을 빠짐없이 방문하는 **완전 탐색 알고리즘**으로, 트리 순회(009)와 달리 그래프에는 사이클(순환 경로)이 존재할 수 있어 방문 이력(Visited)을 반드시 관리해야 무한 루프를 피할 수 있다.
- **왜 필요한가**: 트리는 위계가 있고 루프가 없어 "위에서 아래로만" 가면 저절로 끝나지만, 그래프는 상하 구분이 없고 임의의 정점끼리 연결될 수 있는 거미줄 구조다. 방문한 곳을 기록하지 않으면 같은 자리를 영원히 맴돌 수 있다.
- **핵심 직관**: 미로 찾기에서 한 길로 끝까지 가보는 것이 깊이 우선 탐색(DFS), 갈림길마다 사방으로 한 칸씩 넓혀가며 찾는 것이 너비 우선 탐색(BFS)이다.

## 핵심 용어 정리
| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 정점(Vertex) | 그래프를 구성하는 개별 노드 | 지도의 도시 |
| 간선(Edge) | 두 정점을 잇는 연결선, 방향이 있을 수도(방향 그래프) 없을 수도(무방향 그래프) 있음 | 도시 간 도로 |
| 사이클(Cycle) | 한 정점에서 출발해 같은 정점으로 되돌아오는 경로 | 뱅뱅 도는 순환 도로 |
| 인접 리스트 | 각 정점이 자신과 연결된 정점들의 목록을 갖는 저장 방식, 간선이 적을 때 유리 | 각 도시가 가진 "이웃 도시 목록" |
| 인접 행렬 | V×V 크기의 표에 연결 여부를 0/1로 표시하는 저장 방식, 간선이 많을 때 유리 | 모든 도시 쌍의 연결 여부를 적은 표 |
| Visited 배열(방문 배열) | 각 정점을 이미 방문했는지 True/False로 기록하는 테이블 | 미로에서 지나온 길에 표시하는 분필 자국 |
| DFS(깊이 우선 탐색) | 한 경로를 갈 수 있는 데까지 파고든 뒤 되돌아오는 탐색, 스택 또는 재귀 사용 | 한 길로 끝까지 가보는 미로 탐험 |
| BFS(너비 우선 탐색) | 가까운 정점부터 한 겹씩 넓혀가며 탐색, 큐 사용 | 물결이 동심원으로 퍼지는 모습 |
| 연결 요소(Connected Component) | 서로 도달 가능한 정점들의 묶음 | 섬처럼 떨어진 별개의 네트워크 군집 |
| 백트래킹(Backtracking) | 막다른 길에 도달하면 이전 선택으로 되돌아가 다른 경로를 시도하는 DFS 기반 기법 | 막힌 길에서 갈림길로 되돌아가기 |

## 깊이 이해

### 트리 순회와 무엇이 다른가 — Visited가 필수인 이유
트리(008, 009)는 부모-자식 관계가 명확하고 사이클이 없어서, 한 번 지나간 노드로 다시 돌아올 경로가 원천적으로 없다. 그래서 트리 순회는 방문 기록이 필요 없다. 그러나 그래프는 A→B→C→A처럼 다시 출발점으로 돌아오는 간선이 존재할 수 있다. Visited 배열 없이 순회하면 A→B→C→A→B→C→...를 영원히 반복하는 무한 루프에 빠진다. 그래프 탐색은 "트리 순회 로직 + 사이클 차단 장치(Visited)"의 결합이다.

### DFS와 BFS의 동작 차이 — 자료구조 하나만 다르다
두 알고리즘의 코드는 사실상 동일하다. "다음에 방문할 후보를 어디에 담아뒀다가 꺼내는가"만 다르다. DFS는 스택(또는 재귀 콜스택)에 담기 때문에 가장 최근에 넣은(가장 깊이 들어간) 정점을 먼저 꺼내 계속 파고든다. BFS는 큐에 담기 때문에 가장 먼저 넣은(가장 얕은) 정점을 먼저 꺼내 한 겹씩 넓혀간다. 자료구조 하나를 스택에서 큐로 바꾸는 것만으로 "수직으로 파고드는 탐색"이 "수평으로 퍼지는 탐색"으로 완전히 뒤바뀐다.

### BFS가 최단 경로를 보장하는 이유 — 수치로 확인
BFS는 출발점에서 거리가 1인 정점을 모두 방문한 뒤에야 거리 2인 정점을 방문하기 시작한다(동심원처럼 퍼짐). 예를 들어 출발점 S에서 목표 T까지의 최단 거리가 4홉(hop)이라면, BFS는 거리 1, 2, 3인 정점들을 전부 소진한 뒤에야 거리 4인 정점들을 확인하므로, T를 처음 발견하는 순간이 바로 최단 거리다. 반면 DFS는 한 길로 끝까지 파고들다가 우연히 먼 길을 통해 T에 먼저 도달할 수도 있어, 최단 거리를 보장하지 못한다.

### 공간 복잡도의 함정 — 넓은 그래프에서 BFS가 터지는 이유
BFS는 큐에 "현재 레벨의 모든 정점"을 담아둬야 한다. 만약 각 정점이 평균 10개의 이웃을 갖는 그래프(분기 계수 b=10)에서 깊이 6까지 탐색한다면, 마지막 레벨에만 최대 10^6 = 100만 개의 정점이 큐에 쌓일 수 있다. DFS는 경로 하나만 유지하면 되므로 공간 복잡도가 트리 높이 h에 비례하는 O(h)로 훨씬 작다. 분기가 넓은 그래프(친구 관계망 등)에서 깊은 지점을 찾을 때는 DFS가 메모리 측면에서 안전할 수 있다.

### 한계 극복 — 양방향 탐색과 가중치 확장
BFS의 O(b^d) 메모리 폭발을 줄이는 방법이 양방향 탐색(Bidirectional Search)이다. 출발점과 목표점 양쪽에서 동시에 BFS를 진행해 중간에서 만나면 종료하는 방식으로, 위 예시(b=10, d=6)라면 한쪽은 깊이 3까지만 탐색하면 되므로 2×10^3 = 2,000개 정점만 확인하면 된다 — 100만 개 대비 500배 적은 탐색량이다. 한편 기본 BFS/DFS는 모든 간선을 "거리 1"로 취급하므로 실제 도로 거리나 통신 지연 같은 가중치를 반영하지 못한다. 이 한계를 우선순위 큐로 보완한 것이 다익스트라(011)이며, BFS의 직계 확장으로 볼 수 있다.

### 비유
DFS는 가계도를 조사할 때 한 직계 자손을 증손자까지 끝까지 파악한 뒤 옆 형제로 넘어가는 방식이고, BFS는 "내 1촌들"을 모두 파악한 뒤에야 그들의 1촌인 "2촌들"을 파악하는 친구 추천 알고리즘과 같다.

### 흔한 오해
"BFS가 항상 DFS보다 우월하다"는 오해가 있지만, 목적에 따라 정반대다. 지구 반대편의 목표를 찾는다면 BFS는 메모리가 먼저 고갈될 수 있고, 반대로 가장 가까운 목표를 찾는 문제라면 DFS는 엉뚱한 방향으로 수십 단계를 파고들 수 있어 BFS가 유리하다. "무엇을 찾는가"(가장 가까운 것 vs 아무 경로나)가 선택 기준이다.

## 연결 개념
- 009 이진트리 순회 — 트리 DFS를 사이클이 있는 구조로 일반화한 것 (Visited 배열이 추가된 상위 확장)
- 007 스택·큐·덱 — DFS는 스택/재귀, BFS는 큐를 탐색 엔진으로 사용
- 011 최단 경로 — 가중치를 반영하기 위해 BFS를 우선순위 큐 기반으로 확장한 것(다익스트라)

## Ⅰ. 개요 및 필요성

- 정의: 그래프의 모든 정점을 사이클(순환 경로)에 갇히지 않고 한 번씩 방문하는 탐색 기법으로, 트리 순회(009)의 일반화이자 Visited 배열 관리가 추가된 상위 확장
- 배경: 인접 간선(Edge)이 폐쇄 회로(Cycle)를 형성할 수 있는 그래프 특성상, 제어 없는 맹목적 탐색은 무한 루프를 유발함(트리는 사이클이 없어 009에서는 이 문제가 없음)
- 필요성: 네트워크 라우팅 경로 탐지, 소셜 연관성 분석, 최단 경로 산출 시 연산 자원 고갈을 막기 위해 상태 기록 탐색 필수

## Ⅱ. 구조 및 구성요소 (탐색 엔진)

```text
탐색 시작(Start Node) -> 큐/스택 Push -> 인접 간선(Edge) 스캔 -> Visited(검증) -> 미방문 시 Push 처리 반복
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 상태 배열 (Visited) | 정점의 방문 이력 True/False 기록 테이블 | 사이클 억제 및 탐색 종료 선언의 유일한 트리거 |
| 스택 (Stack) | DFS 엔진: 가장 깊은 노드를 LIFO 방식으로 보관 | 함수 Call Stack(재귀)으로 구현 대체 가능 |
| 큐 (Queue) | BFS 엔진: 동일 깊이 노드를 FIFO 방식으로 보관 | 재귀 불가, 명시적 큐 인스턴스 관리 필요 |
| 인접 리스트/행렬 | 정점 간의 연결(간선) 상태를 메모리에 모델링 | 간선이 적을 땐 리스트, 많을 땐 행렬 최적화 |

> 요약: 두 기법은 "다음 방문 후보를 어떤 보관 그릇(자료구조)에 담았다 뺄 것인가" 단 하나의 차이로 탐색 성질이 완전히 바뀐다.

---

## Ⅲ. 동작원리 및 BFS 최단거리 탐색 흐름도

```text
시작점 큐에 Enqueue -> Dequeue(현재 위치) -> 미방문 정점 모두 Enqueue -> 큐 소진 시 탐색 완전 종료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 초기화 및 시작 | 시작 노드를 Queue에 삽입하고 Visited[Start] = True 마킹 |
| 2 | 노드 인출(Dequeue) | 큐의 Front에서 노드 추출 후 목적지 일치 여부 확인 |
| 3 | 인접 노드 스캔 | 현재 노드와 연결된 간선을 따라 하위 노드 탐색 리스트업 |
| 4 | 조건 필터링 삽입 | 이미 방문한 노드는 버리고, 새로운 노드만 큐에 Enqueue 마킹 |

> 요약: BFS는 거리가 d인 노드를 모두 소진해야 d+1 거리를 탐색하므로, 목표 발견 즉시 그 경로가 "최단 거리"임을 수학적으로 보장한다.

## Ⅳ. DFS vs BFS 심화 비교 및 적용 판단

| 비교 축 | DFS (깊이 우선 탐색) | BFS (너비 우선 탐색) | 선택 기준 |
|:---|:---|:---|:---|
| 검색 방향성 | 한 경로의 바닥 끝까지 도달 (수직적) | 인접한 반경을 넓혀가며 도달 (수평적) | 목표 노드의 예상 위치 |
| 공간복잡도 | 트리의 높이 h만큼 스택 메모리 요구 O(h) | 큐에 동일 깊이 인접 노드 보관 최악 O(V) | 차수가 넓은 그래프는 DFS가 안전 |
| 최단 경로 보장 | 보장 불가 (돌아갈 위험 내재) | 100% 최단 경로 도달 보장 | 비용 최소화 등 목적 제약 여부 |
| 구현 리스크 | 깊이 심화 시 StackOverflow 리스크 | 분기(Branch) 증가 시 OOM(Out of Memory) | 제한된 하드웨어 자원 임계치 |

> 요약: 모든 경우의 수를 백트래킹하여 구하려면 DFS를, 출발점으로부터 타임아웃 방어 최단 경로를 찾아야 하면 BFS를 채택한다.

## Ⅴ. 한계 극복 심화 탐색 아키텍처

| 리스크 | 발생 원인 | 파생 해결 방안 (최적화) | 확인 지표 |
|:---|:---|:---|:---|
| 거대 그래프 BFS OOM | 검색 차수가 넓을 시 큐 사이즈 폭발적 팽창 | 시작/목표점 양쪽에서 동시 BFS를 수행하는 양방향 탐색(Bidirectional) | 큐 최대 적재 카운트 |
| 가중치 적용 불가 | 모든 간선 거리를 동일하게 취급 | 우선순위 큐와 BFS를 결합한 다익스트라(Dijkstra) 알고리즘 스위칭 | 노드 간 비용 가중치 |

> 요약: 일반적 BFS/DFS는 비가중치 전용이므로, 실무 라우팅에서는 힙 정렬 기반의 다익스트라 및 A* 알고리즘으로 상향 확장된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 분산 환경의 가비지 컬렉션(GC): 메모리 힙 상의 Root Set을 시작으로 객체 참조 그래프를 DFS/BFS로 순회하여(Mark-and-Sweep) 고아 객체 고속 색출
2. 서비스 연관 추천 엔진망 스캔: 유저 노드를 기점으로 BFS를 2 Depth 제한(2촌 이내)으로 적용하여 쿼리 타임아웃을 막으며 실시간 친구/상품 추천 도출
3. P2P 네트워크 라우팅 브로드캐스트: 블록체인 등 노드 전파망에서 신규 블록 검증 시 상태 배열(캐시) 기반의 BFS 기법을 활용해 최단 전파(Gossip) 달성

**결론 (2줄):**
- 기술사 판단: 그래프 탐색은 "방문 이력 통제"와 "보관 그릇(스택/큐)"의 결합이며, 네트워크 트래픽 폭증을 방어하려면 탐색 깊이 제한(Depth Limit) 통제가 수반되어야 한다.
- 향후 방향: 초거대 그래프 연산 시 단일 머신 탐색의 한계를 극복하기 위해 분산 하둡/스파크 기반의 병렬 BFS로 인프라가 진화하고 있다.
