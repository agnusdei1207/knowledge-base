# 📖 【암기용】 개념 완전 이해

> 목적: BFS와 DFS를 방문 순서, 자료구조, 적용 문제 차이로 이해하게 만든다.

## 한눈에
- **개요**: 그래프의 정점과 간선을 중복 없이 방문해 연결 관계를 파악하는 알고리즘
- **왜 필요한가**: 최단 거리, 연결 요소, 사이클, 위상 정렬처럼 관계망 문제는 그래프 전체 또는 일부를 체계적으로 방문해야 함
- **핵심 직관**: BFS는 물결처럼 가까운 곳부터 퍼지고, DFS는 한 길을 끝까지 내려간 뒤 되돌아옴

## 깊이 이해
- **배경·문제의식**: 그래프는 순환과 다중 경로가 있어 방문 기록 없이는 무한 반복이 발생함. 탐색 알고리즘은 visited 집합으로 중복 방문을 차단함
- **작동 원리**: BFS는 큐를 사용해 시작점에서 거리 0,1,2 순서로 방문함. DFS는 스택 또는 재귀를 사용해 깊은 경로를 먼저 탐색함
- **비유**: BFS는 소문이 하루 단위로 친구의 친구에게 퍼지는 방식, DFS는 미로에서 한 방향으로 끝까지 가보고 막히면 갈림길로 돌아오는 방식임
- **구체 예시**: 무가중치 그래프에서 BFS는 시작점으로부터 간선 수 최단거리 dist[v]를 최초 방문 시 확정함. DFS는 위상 정렬에서 종료 시간을 사용함
- **흔한 오해·주의점**: DFS는 일반 그래프 최단거리를 보장하지 않음. 간선 가중치가 없을 때 최단 간선 수는 BFS로 계산해야 함

## 연결 개념
- 큐·스택 — BFS와 DFS의 방문 순서를 결정하는 핵심 ADT
- 최단 경로 — BFS는 무가중치 최단거리, Dijkstra는 양수 가중치 최단거리
- 위상 정렬 — DFS 종료 시간 또는 진입차수 큐로 구현

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 그래프 탐색은 visited 관리와 인접 정점 확장을 통해 정점·간선을 체계적으로 방문하는 절차이다.
> 2. **가치**: 인접 리스트 기준 BFS·DFS 모두 시간복잡도 O(V+E), 공간복잡도 O(V)를 가진다.
> 3. **판단 포인트**: 무가중치 최단거리·레벨 탐색은 BFS, 연결성·사이클·위상 정렬은 DFS를 우선 검토한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 정점과 간선을 방문해 그래프의 연결 관계를 분석하는 절차
- 배경: 그래프는 순환과 여러 경로를 포함하므로 방문 기록 없이 탐색하면 중복·무한 반복이 발생함
- 필요성: BFS·DFS는 네트워크 경로, 의존성 분석, 추천 관계 탐색의 기본 절차임

---

## Ⅱ. 구조 및 구성요소

```text
Graph(V,E) -> Adjacent List -> Frontier(Queue/Stack) -> Visited Set
             / BFS: Queue and level distance
             / DFS: Stack and entry/finish time
             / Visited: cycle and duplicate control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Vertex/Edge | 그래프 대상 | V개 정점, E개 간선 |
| Adjacent List | 이웃 정점 저장 | 희소 그래프에 적합, O(V+E) |
| Frontier | 다음 방문 후보 | BFS는 Queue, DFS는 Stack |
| Visited | 중복 방문 방지 | 순환 그래프에서 필수 |

> 요약: 그래프 탐색은 인접 표현, frontier 자료구조, visited 집합의 조합으로 방문 순서를 제어한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
시작 정점 -> visited 표시 -> frontier 삽입 -> 이웃 확인 -> 미방문 삽입 -> 반복 종료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 시작 정점 선택 및 visited 표시 | start in V |
| 2 | Queue 또는 Stack에 삽입 | BFS FIFO, DFS LIFO |
| 3 | 인접 정점 순회 | 각 간선 최대 1~2회 확인 |
| 4 | 미방문 정점 추가·반복 | 모든 도달 정점 visited |

> 요약: BFS와 DFS는 frontier 꺼내는 규칙만 다르고, visited 기반 중복 차단과 인접 정점 확장은 동일하다.

---

## Ⅳ. 특징

| 구분 | BFS | DFS | 수치·판단 기준 |
|:---|:---|:---|:---|
| 자료구조 | Queue | Stack/재귀 | FIFO vs LIFO |
| 방문 순서 | 거리 레벨 순 | 깊은 경로 우선 | BFS 최초 방문 dist 확정 |
| 시간복잡도 | O(V+E) | O(V+E) | 인접 리스트 기준 |
| 대표 활용 | 무가중치 최단거리, 레벨 탐색 | 사이클 탐지, 위상 정렬, SCC | 문제 목표로 선택 |

> 요약: BFS는 거리 계층을 보존하고, DFS는 진입·종료 시간을 활용해 구조적 성질을 분석한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | BFS | DFS | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | Queue, level frontier | Stack/재귀, depth path | 최단 간선 수는 BFS |
| 비용/성능 | O(V+E), 공간 O(V) | O(V+E), 공간 O(V) | 희소 그래프는 인접 리스트 |
| 운영/위험 | frontier 폭증 | recursion depth 증가 | 그래프 폭·깊이 계측 |

> 요약: BFS와 DFS는 같은 O(V+E)이지만 거리 보존, 깊이 분석, 메모리 폭이 선택 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 무한 반복 | visited 누락 | 방문 시점 표준화, cycle test | 중복 방문 카운트 |
| 메모리 폭증 | BFS frontier 급증 | depth limit, bidirectional BFS | frontier size p95 |
| 재귀 초과 | DFS 깊이 h 증가 | iterative DFS, stack limit 설정 | max depth, stack error |

> 요약: 그래프 탐색 리스크는 visited, frontier 크기, DFS 깊이로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 복잡도 | 간선 확인 횟수 2E 이하 | 계측 로그 |
| 정확도 | 연결 요소·거리 배열 기대값 일치 | 테스트 그래프 |
| 운영 | 탐색 제한 시간과 메모리 예산 준수 | 부하 테스트 |

> 요약: 성공 기준은 간선 방문 수, 알고리즘 결과, 제한 자원 준수이다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 영향 분석: 서비스 의존 그래프에서 BFS로 1-hop, 2-hop 영향 범위를 산출
2. 빌드 의존성 검증: DFS color(white/gray/black)로 순환 참조 탐지, cycle 발견 시 배포 차단
3. 권한·추천 탐색: 인접 리스트 + visited로 관계 확장, depth limit 2~3으로 탐색 폭 제한

**결론 (2줄):**
- 기술사 판단: 최단 간선 수와 레벨 확장이 요구되면 BFS, 구조 검증과 깊이 기반 분석은 DFS를 선택함
- 향후 방향: 대규모 그래프는 frontier 분할, bitmap visited, Pregel/Giraph형 분산 반복 처리로 확장해야 함
