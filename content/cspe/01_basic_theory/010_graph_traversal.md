## 핵심 답안

그래프 탐색은 정점과 간선으로 표현된 관계망에서 방문 규칙을 정해 도달성, 경로, 연결 요소, 사이클 같은 구조적 특성을 찾는 알고리즘이며, 대표 방식은 큐 기반의 BFS와 스택·재귀 기반의 DFS임.

```text
Graph(V,E) + Start -> Visit Mark -> Queue/Stack -> Adjacent Expansion -> Result
```

기술사 답안에서는 BFS와 DFS를 시간복잡도만으로 비교하지 말고, **방문 순서가 산출물 의미를 어떻게 바꾸는지**, **방문 표시가 왜 필수인지**, **그래프 표현에 따라 비용이 어떻게 달라지는지**를 설명해야 함.

## BFS와 DFS 비교

| 구분 | BFS | DFS |
|:---|:---|:---|
| 자료구조 | 큐 | 스택 또는 재귀 |
| 방문 방식 | 시작점에서 가까운 정점부터 레벨 순회 | 한 경로를 끝까지 방문 후 되돌아감 |
| 대표 용도 | 무가중 최단 거리, 레벨 탐색, 연결 거리 | 사이클 탐지, 위상 정렬, 컴포넌트 분해, 백트래킹 |
| 메모리 위험 | 넓은 레벨에서 큐 폭증 | 깊은 경로에서 스택 초과 |
| 시간복잡도 | 인접 리스트 기준 `O(V+E)` | 인접 리스트 기준 `O(V+E)` |

무가중 그래프의 최단 간선 수는 BFS가 적합하지만, 가중 최단 경로는 다익스트라·벨만-포드 같은 별도 알고리즘이 필요함.

## 그래프 표현과 비용

| 표현 방식 | 공간 | 탐색 비용 | 선택 기준 |
|:---|:---|:---|:---|
| 인접 리스트 | `O(V+E)` | `O(V+E)` | 희소 그래프, 일반 탐색 |
| 인접 행렬 | `O(V^2)` | 보통 `O(V^2)` | 조밀 그래프, 간선 존재 빠른 확인 |
| 압축 희소 행렬 | `O(V+E)` | 대규모 희소 그래프에 효율 | 그래프 분석, 수치 계산 |
| 비트셋 행렬 | `O(V^2)` 비트 | 집합 연산 빠름 | 조밀 그래프, 병렬 비트 연산 |

그래프 탐색 복잡도는 알고리즘만이 아니라 그래프 표현 방식에 의해 달라지므로, 답안에서는 인접 리스트 기준인지 행렬 기준인지 밝혀야 함.

## 절차 관점

1. **입력 확인**: 정점 수, 간선 수, 방향성, 시작 정점, 그래프 표현 방식을 확인함
2. **방문 상태 초기화**: 방문 배열, 거리, 부모, 색상 상태 등 필요한 메타데이터를 준비함
3. **후보 구조 선택**: BFS는 큐, DFS는 스택 또는 재귀 호출을 사용함
4. **인접 정점 확장**: 현재 정점의 인접 정점을 확인하고 미방문 정점을 후보에 추가함
5. **결과 반환**: 방문 순서, 거리, 부모 배열, 컴포넌트 번호, 사이클 존재 여부를 반환함

방문 표시는 사이클과 다중 경로가 있는 그래프에서 무한 반복과 중복 처리를 막는 핵심 장치임.

## 적용 판단

| 요구사항 | 선택 | 이유 |
|:---|:---|:---|
| 시작점에서 최소 간선 수 거리 | BFS | 레벨 순서가 거리 증가 순서와 일치 |
| 경로 존재 여부만 빠르게 확인 | DFS 또는 BFS | 그래프 구조와 메모리 조건에 따라 선택 |
| 사이클 탐지 | DFS | 재귀 스택 또는 색상 상태로 역방향 간선 확인 |
| 위상 정렬 | DFS 또는 진입차수 기반 BFS | 방향 비순환 그래프 조건 확인 |
| 연결 요소 분해 | BFS/DFS 반복 | 미방문 정점을 새 시작점으로 처리 |
| 대규모 관계망 분석 | 병렬 BFS, 분산 그래프 처리 | 프론티어 크기와 통신 비용 관리 |

## 오해와 감점 포인트

- **방문 표시 누락**: 사이클이 있는 그래프에서는 무한 반복이나 중복 처리 폭증이 발생함
- **BFS 최단 경로 오해**: BFS는 무가중 그래프에서 최단 간선 수를 보장하며, 가중 그래프에는 별도 알고리즘이 필요함
- **그래프 표현 누락**: 인접 리스트와 인접 행렬의 시간·공간 비용이 다름
- **DFS 재귀 위험 누락**: 깊은 그래프에서는 호출 스택 초과가 발생할 수 있음
- **연결 그래프 가정**: 비연결 그래프에서는 모든 정점을 시작점 후보로 반복 탐색해야 함

## 운영 리스크와 대응

| 리스크 | 대응 |
|:---|:---|
| 큐·스택 메모리 증가 | 레벨별 프론티어 제한, 반복 DFS, 깊이 제한 |
| 중복 후보 삽입 | 후보에 넣는 시점에 방문 표시 |
| 대규모 그래프 I/O 병목 | 압축 표현, 파티셔닝, 배치 확장 |
| 방향 그래프 사이클 누락 | 색상 상태 또는 재귀 스택 상태 관리 |
| 결과 복원 불가 | 부모 배열과 거리 배열을 함께 저장 |

## 답안 작성 포인트

1. 정의는 "방문 규칙으로 그래프의 도달성·경로·구조를 찾는 알고리즘"으로 씀
2. BFS와 DFS를 큐/스택, 방문 순서, 대표 용도 기준으로 비교함
3. 인접 리스트 기준 `O(V+E)`와 인접 행렬 기준 비용 차이를 명시함
4. 방문 표시의 필요성을 사이클과 중복 경로 관점에서 설명함
5. 결론은 "같은 복잡도라도 산출물과 자원 특성이 달라 요구사항에 맞게 선택한다"로 마무리함

> 기술사 관점에서 그래프 탐색은 BFS·DFS 암기가 아니라 관계 데이터에서 어떤 구조 정보를 산출할 것인지에 따라 방문 규칙과 표현 방식을 선택하는 문제임.
