## Ⅰ. 개요
- **정의**: 그래프의 모든 정점을 체계적으로 방문하는 탐색 알고리즘으로, DFS(깊이 우선)와 BFS(너비 우선)로 구분됨
- **배경/필요성**: 그래프는 순환과 다중 경로가 존재하여 방문 여부를 추적하지 않으면 무한 루프가 발생하므로, 체계적 탐색 전략이 요구됨
- **비유**: 미로 탈출 — DFS는 한 길을 끝까지 가본 뒤 막히면 되돌아오고, BFS는 갈림길마다 모든 방향을 한 걸음씩 동시에 확장함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DFS·BFS의 동작 원리와 적용 차이 | DFS: 스택/재귀, BFS: 큐. 시간복잡도 O(V+E) | 인접 행렬 O(V^2) vs 인접 리스트 O(V+E) 표현 차이를 명시할 것 |

> 요약: DFS(스택 기반 깊이 우선)와 BFS(큐 기반 너비 우선)로 그래프 전체를 체계적으로 탐색함

## Ⅱ. 구성요소
```text
  그래프 표현                    탐색 방식
  +-----------+                 +-------+-------+
  | 인접 행렬 |  O(V^2) 공간    | DFS   | BFS   |
  | 인접 리스트|  O(V+E) 공간    | Stack | Queue |
  +-----------+                 | 재귀  | 레벨  |
                                +-------+-------+
  방문 배열: visited[V] --- 중복 방문 방지
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DFS | 스택(007 참조) 또는 재귀로 한 경로를 끝까지 탐색 후 백트래킹하는 방식 | 미로에서 한 길을 끝까지 가보고 막히면 되돌아옴 |
| BFS | 큐(007 참조)로 현재 정점의 인접 정점을 모두 방문한 뒤 다음 레벨로 진행하는 방식 | 물결 파동 — 중심에서 동심원으로 퍼져나감 |
| 인접 행렬 | V x V 2차원 배열로 간선 존재 여부를 저장, 간선 조회 O(1)이나 공간 O(V^2) | 전체 좌석 배치표 — 모든 조합을 기록 |
| 인접 리스트 | 각 정점별로 연결된 정점 목록을 저장, 공간 O(V+E)이나 간선 조회 O(degree) | 연락처 목록 — 아는 사람만 기록 |
| `visited` 배열 | 각 정점의 방문 여부를 기록하여 중복 방문과 무한 루프를 방지 | 방문 도장 — 이미 간 곳에 표시 |

> 요약: DFS(스택)·BFS(큐)가 인접 행렬/리스트와 visited 배열을 활용하여 그래프를 탐색함

## Ⅲ. 절차
```text
  시작 정점 선택       인접 정점 탐색       방문 처리           종료 판단
  (visited 초기화)    (DFS:스택/BFS:큐)   (visited 갱신)     (미방문 정점 확인)
       |                   |                  |                  |
       +---시작 push/enq-->+---인접 순회------>+---방문 기록------>+
     시작 정점 방문      간선 따라 이동     중복 방문 차단     모든 정점 방문 시 종료
```
- 1단계: 시작 정점을 선택하고 `visited` 배열을 초기화한 뒤 스택(DFS) 또는 큐(BFS)에 삽입함
- 2단계: 현재 정점의 인접 정점을 순회하며 미방문 정점을 스택/큐에 추가함
- 3단계: 꺼낸 정점을 `visited`로 표시하여 중복 방문을 차단하고 처리(출력·연산 등)함
- 4단계: 스택/큐가 비면 탐색을 종료하고, 비연결 그래프의 경우 미방문 정점에서 재시작함

> 요약: 시작 정점 → 인접 탐색 → 방문 처리 → 종료 판단의 4단계로 O(V+E)에 탐색 완료함

## Ⅳ. 문제점
- DFS 스택 오버플로: 재귀 구현 시 정점 수가 많으면 콜스택 한계 초과 — 대규모 그래프에서 런타임 오류 발생
- BFS 메모리 사용: 너비가 넓은 그래프에서 큐에 동시 저장되는 정점 수가 O(V)에 도달 — 메모리 부족 발생 가능
- 인접 행렬 공간 낭비: 희소 그래프(간선 수 << V^2)에서 O(V^2) 공간 중 대부분이 0으로 채워짐 — 메모리 비효율

> 요약: DFS 스택 한계, BFS 큐 메모리, 인접 행렬 공간 낭비가 주요 제약임

## Ⅴ. 개선방안
1. 단기: DFS를 명시적 스택 기반 반복으로 구현하여 콜스택 오버플로 방지
2. 중기: BFS에서 양방향 탐색(Bidirectional BFS)을 적용하여 탐색 범위를 절반으로 축소
3. 장기: 희소 그래프에 인접 리스트 + 압축 희소 행(CSR) 포맷을 적용하여 공간 O(V+E)로 절감

> 요약: 반복 DFS → 양방향 BFS → CSR 포맷으로 스택·메모리·공간 문제를 단계적 해소함

## Ⅵ. 전망
- 발전 방향: 분산 그래프 처리 프레임워크(Pregel, GraphX)에서 BFS/DFS 기반 병렬 탐색이 확산됨
- 기술사적 판단: DFS(위상 정렬·강연결 요소)와 BFS(최단 경로·네트워크 분석)의 용도를 구분하여 적용하는 역량이 핵심임
- 기술사 제언: 그래프 규모·밀도·목적에 따라 표현 방식(행렬/리스트)과 탐색 전략(DFS/BFS)을 체계적으로 선정할 필요
