## Ⅰ. 개요

- **개요**: 그래프 탐색은 정점·간선으로 이뤄진 그래프의 모든 정점을 빠짐없이, 중복 없이 방문하는 절차임.
- **배경/필요성**: 트리는 부모→자식 방향의 단일 경로만 있어 순회 규칙(전위·중위·후위)만 정하면 되지만, 그래프는 사이클과 비연결 요소가 존재해 같은 정점을 되돌아 만나거나 일부 정점에 아예 도달하지 못할 수 있음. 따라서 순회 규칙 외에 "이미 방문한 정점"을 별도로 기록하는 장치가 추가로 필요함.
- **출제 의도**: BFS·DFS의 방문 순서 차이와 그 차이를 만드는 자료구조(큐 vs 스택/재귀)를 구분하는 능력, 방문 기록(visited) 관리를 누락했을 때 발생하는 문제를 판단하는 역량, 그래프 표현 방식(인접 리스트·인접 행렬)이 탐색 성능에 미치는 영향을 이해하는지 확인함.
- **답안 방향**: 정의 및 트리 순회와의 차이(방문 기록 필요성)를 먼저 짚고(Ⅰ), BFS·DFS의 구조와 구성요소를 구분하며(Ⅱ), 큐·스택 기반 실행 절차를 서술한 뒤(Ⅲ), 최단경로 보장 여부·적용 문제 유형 기준의 심화 비교로 이어가는(Ⅴ) 축으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| BFS·DFS 방문 순서 차이와 구현 자료구조 구분 능력 확인 | 큐 기반 BFS는 층별 탐색으로 최단경로(가중치 없는 그래프) 보장, 스택·재귀 기반 DFS는 한 경로를 끝까지 깊이 탐색 | 두 알고리즘의 시간복잡도가 서로 다르다고 단정(둘 다 인접 리스트 기준 O(V+E)로 동일) |
| 방문 기록(visited) 관리 필요성 판단 | 사이클·비연결 요소가 있는 그래프에서 visited 없이 탐색하면 무한 루프 또는 중복 방문 발생 | "트리 순회처럼 방문 기록 없이도 순회가 끝난다"는 식의 단정 |
| 그래프 표현 방식에 따른 구현·성능 차이 이해 | 인접 리스트는 O(V+E), 인접 행렬은 O(V^2) 순회 비용 | 표현 방식과 무관하게 탐색 성능이 항상 동일하다고 단정 |

> 요약: 이 답안은 그래프가 트리와 달리 사이클·비연결 요소를 가진다는 구조적 차이에서 "방문 기록"이라는 장치가 왜 필요한지를 짚고, 그 위에서 BFS·DFS의 자료구조·성능 차이를 판단하는 축으로 전개함.

## Ⅱ. 구조 및 구성요소

```text
그래프 입력(정점·간선) -> 표현 방식 선택(인접 리스트/인접 행렬) -> 방문 배열(visited) 초기화
                                                                    |
                                                                    +-> BFS: 큐에 시작 정점 삽입 -> 층별 확장
                                                                    +-> DFS: 스택/재귀로 한 경로 끝까지 하강
                                                                    |
                                                                    +-> 역방향 간선 만나면 사이클 판정
                                                                    +-> 미방문 정점 남으면 새 연결요소로 재시작
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 인접 리스트 | 정점마다 연결된 이웃만 배열/리스트로 저장 | 순회 비용 $O(V+E)$, 이웃만 적어둔 주소록 |
| 인접 행렬 | `V x V` 배열에 간선 존재 여부를 0/1로 저장 | 순회 비용 $O(V^2)$, 두 정점 간 연결을 표 하나로 즉시 조회하는 좌석 배치도 |
| 방문 배열(visited) | 정점별 방문 여부를 기록해 재방문을 차단 | 무한 루프·중복 방문을 막는 출입 체크 명단 |
| BFS 큐(Queue) | 선입선출로 인접 정점을 층 단위로 적재 | 가중치 없는 그래프에서 최단경로를 보장하는 근거 |
| DFS 스택/재귀 | 후입선출로 한 경로를 막다른 곳까지 파고든 뒤 되짚어 나옴(백트래킹) | 갈림길마다 표식을 남기고 되돌아오는 탐험가 |
| 연결요소(Connected Component) | 탐색을 마친 뒤에도 방문 배열에 남은 미방문 정점들의 집합 | 그래프가 몇 개의 독립된 조각으로 나뉘는지 알려주는 지표 |
| 역방향 간선(Back Edge) | DFS 탐색 중 현재 경로상의 조상 정점을 다시 가리키는 간선 | 사이클 존재를 판정하는 유일한 신호 |

> 요약: 그래프 표현 방식(인접 리스트/행렬)이 저장·순회 비용을 결정하고, 방문 배열이 재방문을 차단하는 위에서 BFS 큐·DFS 스택/재귀가 층별·심층 탐색을 가르며, 그 결과가 연결요소 개수와 역방향 간선 유무 판정으로 이어짐.

## Ⅲ. 동작원리 및 흐름도

```text
예시 그래프(인접 리스트, 정점당 이웃을 오름차순 저장):
1: [2,3]   2: [1,4]   3: [1,4,5]   4: [2,3]   5: [3,6]   6: [5]

BFS(시작 1, 큐): 1 방문 -> 2,3 인큐 -> 2 방문(4 인큐) -> 3 방문(5 인큐) -> 4 방문 -> 5 방문(6 인큐) -> 6 방문
  방문 순서: 1 -> 2 -> 3 -> 4 -> 5 -> 6   (층: {1} / {2,3} / {4,5} / {6})

DFS(시작 1, 스택/재귀): 1 방문 -> 2 방문 -> 4 방문(2의 다음 미방문 이웃) -> 3 방문(4의 미방문 이웃) -> 5 방문 -> 6 방문 -> 더 갈 곳 없어 역순 반환
  방문 순서: 1 -> 2 -> 4 -> 3 -> 5 -> 6
```

- 1단계 초기화: 시작 정점을 정하고 `visited` 배열을 전부 미방문으로 두되 시작 정점만 즉시 방문 처리함.
- 2단계 자료구조 적재: BFS는 시작 정점을 큐에 넣고, DFS는 스택에 넣거나 재귀 호출 인자로 넘김.
- 3단계 이웃 확장: 큐/스택에서 정점 하나를 꺼내 인접 리스트를 순서대로 훑어 미방문 이웃만 `visited` 처리 후 다시 적재하되, BFS는 큐 뒤쪽에 넣어 같은 층 정점을 다 꺼낸 뒤에야 다음 층으로 넘어가고 DFS는 스택 위(또는 재귀의 다음 호출)에 넣어 방금 방문한 정점의 이웃을 바로 이어서 파고듦 — 위 예시에서 BFS가 2 다음 3을 바로 방문하는 반면 DFS는 2->4를 먼저 타고 내려간 뒤에야 3에 도달하는 차이가 여기서 갈림.
- 4단계 종료 판정: 큐/스택이 비면 현재 연결요소 탐색을 종료하고, `visited`에 미방문 정점이 남아 있으면 그 정점을 새 시작점으로 2단계부터 재시작하며, 모두 방문됐으면 전체 탐색을 끝냄.

> 요약: 같은 인접 리스트와 `visited` 위에서 정점을 꺼낸 뒤 다시 넣는 자료구조만 큐↔스택/재귀로 바꾸면, 위 예시 그래프에서 BFS는 1-2-3-4-5-6(층별)로 DFS는 1-2-4-3-5-6(깊이 우선)으로 방문 순서가 갈림.

## Ⅳ. 특징

- 시간복잡도가 같은 근거: 인접 리스트 기준으로 BFS·DFS 모두 $O(V+E)$인 것은 자료구조 종류(큐/스택)가 아니라, 두 알고리즘 다 각 정점을 정확히 한 번 꺼내고 그때 그 정점의 인접 리스트를 한 번만 훑는 순회 구조 자체에서 비롯됨.
- 공간 점유 패턴 차이: BFS는 같은 층의 정점을 큐에 한꺼번에 적재해 최악의 경우 그래프 폭만큼 메모리를 점유하고, DFS는 재귀/스택에 현재 경로 위 정점만 쌓아 깊이만큼만 점유하므로, 폭이 넓고 깊이가 얕은 그래프일수록 DFS가 순간적으로 더 적은 메모리를 사용함.
- BFS 최단경로 보장의 한계: 층 단위 방문 순서가 최단 거리와 일치하는 것은 간선 가중치가 모두 같거나 없는 전제에서만 성립하며, 가중치가 서로 다르면 나중 층에서 방문한 정점이 실제로는 더 짧은 거리를 가질 수 있어 다익스트라(Dijkstra) 등 별도 알고리즘으로 대체해야 함.
- `visited` 부재 시 실패 양상 차이: 사이클이 있는 그래프에서 `visited` 배열 없이 탐색하면 BFS는 같은 정점을 반복 인큐(enqueue)하며 큐 크기가 무한히 늘어나고, 재귀 기반 DFS는 같은 경로를 반복 호출하며 콜 스택이 무한히 쌓여 스택 오버플로우로 비정상 종료됨.

> 요약: BFS·DFS는 시간복잡도($O(V+E)$)는 같지만, 공간 점유 패턴(폭 대 깊이), 최단경로 보장 조건(무가중치 한정), `visited` 누락 시 실패 양상(큐 폭주 대 스택 오버플로우)에서 갈림.

## Ⅴ. 심화 비교 및 적용 판단

| 적용 문제 유형 | BFS | DFS | 선택 기준 |
|:---|:---|:---|:---|
| 최단 경로가 필요한가 | 무가중치 그래프에서 보장(층 단위 방문) | 보장 안 함(경로 하나를 끝까지 파고들 뿐) | 무가중치 최단 거리가 목적이면 BFS |
| 메모리 제약이 있는가 | 최악 그래프 폭만큼 큐 점유 | 최악 그래프 깊이만큼만 스택 점유 | 폭이 넓고 깊이가 얕으면 DFS가 순간 메모리 유리 |
| 존재 여부만 판정하면 되는가(경로 전체 나열, 위상 정렬 등) | 층 정보가 필요 없으면 과잉 | 백트래킹으로 전체 경로 나열·사이클 판정에 적합 | 경로 자체를 다뤄야 하면 DFS |

> 요약: 무가중치 최단 거리가 목적이면 BFS, 메모리 제약 하에 경로·사이클을 다뤄야 하면 DFS를 선택함.

**리스크·대응 (불릿):**
- 가중치 그래프에 BFS를 그대로 적용해 "층 순서 = 최단 거리"로 오판하는 리스크 → 가중치가 있으면 다익스트라 등 별도 알고리즘으로 대체 (지표: 간선 가중치 동일 여부 사전 확인)
- 대규모 그래프에서 재귀 DFS 사용 시 스택 오버플로우 리스크 → 명시적 스택으로 반복 구현하거나 재귀 깊이 상한을 사전 점검 (지표: 최대 재귀 깊이, 그래프 최장 경로 길이)

**도입 후 점검 지표 (불릿):**
- 정확성: 전체 정점 방문 여부(연결요소 누락 없음)를 테스트 그래프로 검증
- 성능: 실측 방문 시간이 $O(V+E)$ 상한 내에 수렴하는지 정점·간선 수 대비 측정

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 그래프의 가중치 유무·규모를 진단해 BFS/DFS 중 기본 정책과 인접 리스트/행렬 표현 방식을 결정함
2. 중기: 대규모 그래프의 재귀 DFS를 명시적 스택 기반 반복 구현으로 전환해 스택 오버플로우 위험을 제거함
3. 장기: 가중치 그래프·최단 경로 요구가 늘어나면 다익스트라·벨만-포드 등 확장 알고리즘 도입 기준을 운영 정책에 반영함

- 기술사적 판단: 무가중치 최단 거리는 BFS, 경로·사이클 자체를 다뤄야 하면 DFS를 기본 선택지로 하되, 두 경우 모두 `visited` 관리 없이는 정확성이 성립하지 않음
- 기술사 제언: 그래프 탐색 도입 시 "가중치가 있는가"라는 질문 하나로 BFS/DFS 계열과 다익스트라 계열의 적용 범위가 갈리므로, 이 판단을 설계 문서에 먼저 명시해야 함
