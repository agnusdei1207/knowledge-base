# 010. 그래프 탐색 — BFS·DFS (Graph Traversal)

## 미리 알고가기

- **정점(Vertex)과 간선(Edge)**: 데이터를 담는 객체와 그들 사이의 관계를 나타내며, 각각 $V$와 $E$로 표기함
- **방문 배열 (Visited Array)**: 이미 방문한 정점을 기록하여 무한 루프(사이클)에 빠지는 것을 방지하는 장치임
- **인접 리스트 (Adjacency List)**: 각 정점에 연결된 정점들을 리스트로 관리하여 메모리 효율성을 높인 그래프 표현 방식임

## 1. 개요

- **정의/개념**: 그래프 탐색은 시작 정점으로부터 간선을 따라 모든 정점을 빠짐없이 한 번씩 방문하는 과정이며, 방문 순서와 자료구조에 따라 BFS(너비 우선)와 DFS(깊이 우선)로 분류됨
- **배경/필요성**: 복잡하게 얽힌 관계형 데이터(소셜 네트워크, 네트워크 토폴로지)에서 특정 정점까지의 최단 거리, 사이클 존재 여부, 연결된 컴포넌트 식별 등을 수행하기 위한 알고리즘의 기초임

## 2. 특징 및 비교

BFS와 DFS는 다음에 방문할 후보 정점을 저장하는 자료구조(Queue vs Stack)의 차이로 인해 탐색의 방향성과 문제 해결 영역이 달라짐.

| 비교 항목 | BFS (Breadth-First Search) | DFS (Depth-First Search) |
|:---|:---|:---|
| **자료구조** | **큐 (Queue)**를 이용한 반복문 구현 | **스택 (Stack)** 또는 **재귀(Recursion)** |
| **탐색 방식** | 현재 층의 모든 이웃을 먼저 탐색 (수평) | 한 경로를 끝까지 탐색 후 되돌아옴 (수직) |
| **최단 경로** | **가중치 없는 그래프에서 최단 거리 보장** | 최단 거리 보장 불가 |
| **메모리 특징** | 인접 노드가 많을 때 큐 메모리 급증 | 탐색 깊이가 깊을 때 스택 오버플로우 위험 |
| **시간복잡도** | $O(V+E)$ (인접 리스트 기준) | $O(V+E)$ (인접 리스트 기준) |
| **주요 용도** | 최단 경로, 최소 신장 트리, 레벨 순회 | 사이클 탐지, 위상 정렬, 백트래킹, 미로 탐색 |

> 요약: 거리(Hop) 중심의 문제 해결에는 BFS, 경로의 성질(사이클 등) 분석에는 DFS를 선택함.

## 3. 구성요소/구조

탐색 알고리즘은 현재 상태를 파악하고, 다음 전이(Transition) 대상을 결정하며, 중복 방문을 통제하는 로직으로 구성됨.

- **구성요소**:
  - **시작 정점 (Root)**: 탐색이 시작되는 진입점
  - **프런티어 (Frontier)**: 다음에 방문할 예정인 정점들의 집합 (Queue 또는 Stack)
  - **방문 처리 (Marking)**: 중복 방문 방지를 위한 상태 기록 ($True/False$)
  - **인접 표현**: 정점 간의 연결 정보를 담고 있는 데이터 구조

- **탐색 원리 (ASCII 흐름도)**:

```text
[BFS: 층별 확산]                    [DFS: 끝까지 탐색 후 복귀]
     (A) - Level 0                   (A) 1. 시작
    /   \                            |
  (B)---(C) - Level 1                (B) 2. 하향
  / \     \                          |
(D) (E)---(F) - Level 2              (C) 3. 더 갈 곳 없으면 복귀(Backtrack)
```

1. **BFS 절차**: 시작 노드를 큐에 넣고 방문 처리 -> 큐에서 하나씩 꺼내어 인접 노드 중 미방문 노드를 모두 큐에 삽입하고 방문 처리 -> 반복
2. **DFS 절차**: 시작 노드를 방문 처리하고 재귀 호출(또는 스택 삽입) -> 인접 노드 중 미방문 노드가 있으면 즉시 깊게 들어감 -> 더 이상 갈 곳이 없으면 이전 정점으로 복귀

## 4. 문제점 및 개선방안

1. **DFS의 스택 오버플로우 (Stack Overflow)**: 그래프의 깊이가 수만 개 이상일 경우 시스템 재귀 한계를 초과하여 프로그램이 비정상 종료됨
   - **개선방안**: 재귀 호출 대신 명시적 스택(Explicit Stack) 자료구조를 사용하는 반복문 기반 DFS로 전환하거나, 시스템의 재귀 깊이 제한을 조정함 (확인: 최대 탐색 깊이 프로파일링)

2. **BFS의 과도한 메모리 점유**: 정점의 차수(Degree)가 큰 그래프에서 한 번에 큐에 담기는 후보 노드가 많아져 메모리가 부족해질 수 있음
   - **개선방안**: 메모리가 부족할 경우 탐색 범위를 제한하는 IDDFS(반복적 깊이 제한 탐색)를 고려하거나, 필요한 구간만 탐색하는 양방향 탐색(Bidirectional Search)을 적용함 (확인: 피크 타임 큐 크기)

3. **중복 방문 통제 실패**: 방문 처리를 큐에서 꺼낼 때(Pop) 수행하면, 동일 노드가 큐에 중복 삽입되어 연산량이 지수적으로 증가함
   - **개선방안**: 노드를 **큐/스택에 넣는 시점(Push)**에 즉시 방문 처리하도록 로직을 교정하여 중복 삽입을 원천 차단함 (확인: 방문 배열 갱신 시점 검증)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 네트워크 라우팅 | 최단 홉(Hop) 수 기반의 경로 설정을 위해 BFS 기반의 거리 계산 수행 | 경로 도달 시간, 홉 카운트 |
| 소스 코드 정적 분석 | 함수 호출 관계 그래프에서 DFS로 순환 참조(Circular Reference)를 탐지하여 빌드 오류 방지 | 사이클 탐지 여부, 분석 소요 시간 |
| 검색 엔진 크롤러 | 웹 페이지의 링크를 타고 탐색할 때 층별로 긁을지(BFS) 한 사이트를 파고들지(DFS) 결정하여 수집 정책 수립 | 페이지 수집량, 도메인 점유율 |
| 2D 격자 맵 (게임/GIS) | 미로 찾기나 영역 채우기(Flood Fill) 수행 시 연결된 영역을 탐색하여 경계 식별 | 탐색 속도, 메모리 사용량 |

> 요약: 무가중치 최단 거리 탐색에는 BFS, 복잡한 경로 및 관계 분석에는 DFS가 표준임.

## 6. 결론

그래프 탐색은 비정형 관계형 데이터를 분석하기 위한 가장 핵심적인 알고리즘적 도구임. 기술사는 BFS와 DFS의 시간복잡도가 동일하게 $O(V+E)$임에도 불구하고, 각 알고리즘이 자료구조의 특성상(FIFO vs LIFO) 가져오는 탐색 전략의 차이를 명확히 이해하고 문제 상황에 맞게 선택할 수 있어야 함.

최근의 대규모 그래프 처리 시스템(Graph DB 등)에서는 단순 탐색을 넘어 병렬 처리, 분산 탐색, 그리고 메모리 최적화 기법이 결합된 형태의 탐색 알고리즘이 요구됨. 따라서 알고리즘의 동작 원리뿐만 아니라, 실제 운영 환경에서의 메모리 제약과 최악의 데이터 구조(Skewed Graph 등)에 대한 대응 방안을 함께 고려하는 설계적 안목이 필수적임.
