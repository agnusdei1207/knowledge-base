## Ⅰ. 개요
- **정의**: 그래프의 모든 정점을 체계적으로 방문하는 알고리즘
- **배경/필요성**: 네트워크 경로 탐색, 연결 요소 판별, 사이클 탐지 등 그래프 기반 문제 해결에 정점 방문 순서를 결정하는 탐색 기법이 필수적임
- **비유**: 미로에서 출구를 찾을 때, 한 방향으로 끝까지 가보는 방식(DFS)과 현재 위치에서 갈 수 있는 곳을 한 칸씩 펼쳐보는 방식(BFS)의 차이와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| BFS와 DFS의 동작 원리·자료구조·활용 차이 | BFS는 큐+최단 경로, DFS는 스택+사이클 탐지 | 시간복잡도 O(V+E)의 도출 근거와 인접 리스트 전제 명시 |

> 요약: BFS는 큐로 너비 우선 탐색하여 최단 경로를 보장하고, DFS는 스택/재귀로 깊이 우선 탐색하여 사이클을 탐지함

## Ⅱ. 구성요소
```text
        Graph(V, E)
       /           \
  [BFS]            [DFS]
  Queue 사용        Stack/재귀 사용
  레벨 단위 확장    깊이 우선 확장
      |                |
  최단 경로 보장    백트래킹/사이클 탐지

그래프 표현:
  인접 행렬 ---> V x V 2차원 배열, 공간 O(V^2)
  인접 리스트 -> 각 정점별 연결 리스트, 공간 O(V+E)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| BFS(너비 우선 탐색) | 큐에 시작 정점을 넣고 인접 정점을 레벨 단위로 확장하며 방문함 | 돌을 던져 수면에 퍼지는 동심원처럼 가까운 곳부터 탐색함 |
| DFS(깊이 우선 탐색) | 스택 또는 재귀로 한 경로를 끝까지 탐색한 뒤 백트래킹함 | 한 갈래길을 막다른 곳까지 가본 뒤 되돌아오는 방식 |
| 인접 행렬 | V×V 크기의 2차원 배열로 간선 유무를 `1`/`0`으로 표현함 | 모든 사람 간 관계를 표로 정리한 전체 대조표 |
| 인접 리스트 | 각 정점마다 연결된 정점 목록을 리스트로 저장함 | 각 사람의 연락처 목록만 따로 관리하는 방식 |
| 방문 배열(`visited`) | 각 정점의 방문 여부를 기록하여 중복 방문과 무한 루프를 방지함 | 미로 벽에 방문 표시를 남기는 것과 유사함 |

> 요약: BFS·DFS는 큐와 스택이라는 자료구조 차이로 탐색 순서가 결정되며, 그래프는 인접 행렬 또는 인접 리스트로 표현됨

## Ⅲ. 절차
```text
[그래프 입력] --> [시작 정점 선택] --> [자료구조 초기화] --> [탐색 수행]
                                       |                      |
                                  BFS: 큐 + visited       인접 정점 확장
                                  DFS: 스택 + visited      백트래킹
```
- 1단계: 그래프를 인접 리스트 또는 인접 행렬로 입력받고, 시작 정점을 지정함
- 2단계: `visited` 배열을 초기화하고, BFS는 큐에, DFS는 스택에 시작 정점을 삽입함
- 3단계: 큐/스택에서 정점을 꺼내 방문 처리하고, 미방문 인접 정점을 큐/스택에 추가함
- 4단계: 큐/스택이 빌 때까지 3단계를 반복함. 시간복잡도 O(V+E), 공간복잡도 O(V)

> 요약: 시작 정점에서 큐 또는 스택을 이용해 인접 정점을 확장하며 O(V+E)에 전체 탐색을 완료함

## Ⅳ. 문제점
- DFS 스택 오버플로: 재귀 기반 DFS에서 정점 수가 많은 그래프는 콜스택 한계를 초과할 수 있음(이진트리 순회의 편향 문제와 동일, 009 참조)
- BFS 메모리 폭증: 분기 계수(branching factor)가 큰 그래프에서 큐에 동시 저장되는 정점 수가 급격히 증가함
- 인접 행렬 공간 낭비: 희소 그래프(E << V^2)에서 O(V^2) 공간을 할당하면 대부분이 `0`으로 채워져 메모리가 낭비됨

> 요약: 재귀 DFS의 스택 한계, BFS의 큐 메모리 폭증, 희소 그래프에서 인접 행렬의 공간 낭비가 주요 문제임

## Ⅴ. 개선방안
1. 단기: DFS를 명시적 스택 기반 반복 방식으로 전환하여 콜스택 오버플로를 방지함
2. 중기: 양방향 BFS(Bidirectional BFS)를 적용하여 탐색 범위를 절반으로 줄이고 큐 메모리 사용량을 감소시킴
3. 장기: 희소 그래프에는 인접 리스트를, 밀집 그래프에는 인접 행렬을 선택하는 적응형 표현 전략을 수립함

> 요약: 반복 DFS로 안정성을 확보하고, 양방향 BFS와 적응형 그래프 표현으로 메모리 효율을 개선함

## Ⅵ. 전망
- 발전 방향: 대규모 그래프(소셜 네트워크, 웹 크롤링)에서 분산 BFS/DFS와 외부 메모리 탐색 기법이 확산됨
- 기술사적 판단: BFS·DFS는 최단 경로(011 참조), 최소 신장 트리(012 참조) 등 고급 그래프 알고리즘의 기반이므로 중요도가 지속됨
- 기술사 제언: 탐색 알고리즘 선택 시 그래프 밀도·목적(경로 탐색/사이클 탐지/연결 판별)에 따른 BFS·DFS 사용 기준을 수립할 필요가 있음
