## 미리 알고가기

- 정점: 그래프에서 대상 객체나 상태를 나타내는 노드임
- 간선: 정점 사이의 관계나 이동 가능성을 나타내는 연결임
- 방문 표시: 같은 정점을 반복 처리하지 않기 위해 기록하는 상태임
- BFS: 큐를 사용해 가까운 정점부터 층별로 방문하는 탐색임
- DFS: 스택 또는 재귀를 사용해 한 경로를 깊게 따라가는 탐색임

## Ⅰ. 개요

- **정의**: 그래프 탐색은 정점과 간선으로 표현된 관계망에서 시작 정점 또는 전체 정점을 기준으로 도달 가능한 정점과 경로 구조를 찾아내는 알고리즘임. BFS와 DFS는 각각 큐 기반의 너비 우선, 스택 기반의 깊이 우선 방문 규칙을 사용해 연결성, 최단 단계 수, 사이클, 위상 관계를 판단하기 위해 사용함.
- **배경/필요성**: 그래프는 트리와 달리 사이클과 다중 경로가 있을 수 있어 방문 표시가 필수임. 탐색 방식 선택은 원하는 결과가 최단 레벨인지, 모든 경로 탐색인지, 컴포넌트 분해인지에 따라 달라짐.
- **비유**: BFS는 주변 골목부터 동심원처럼 넓히는 수색이고, DFS는 한 골목 끝까지 들어갔다가 되돌아오는 수색과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 그래프 기본 알고리즘 선택 역량 확인 | 정점/간선, 방문 표시, 큐/스택, `O(V+E)` | 방문 표시 누락, BFS/DFS 용도 혼동 |

> 요약: 그래프 탐색은 방문 규칙을 정해 관계망의 도달성, 경로, 구조적 특성을 확인하는 알고리즘임.

## Ⅱ. 특징/비교

| 판단 기준 | BFS | DFS | 선택 기준 |
|:---|:---|:---|:---|
| 자료구조 | 큐 | 스택 또는 재귀 | 방문 순서 구현 방식 |
| 방문 순서 | 시작점에서 가까운 정점부터 층별 방문 | 가능한 경로를 끝까지 방문 후 되돌아감 | 레벨 정보 필요 여부 |
| 대표 용도 | 무가중 최단 거리, 레벨 탐색 | 사이클 탐지, 위상 정렬, 백트래킹 | 결과 의미에 따라 결정 |
| 메모리 특성 | 넓은 층에서 큐가 커질 수 있음 | 깊은 경로에서 스택이 커질 수 있음 | 그래프 폭과 깊이 고려 |
| 시간 복잡도 | 인접 리스트 기준 `O(V+E)` | 인접 리스트 기준 `O(V+E)` | 비용은 같아도 산출물이 다름 |

> 요약: BFS와 DFS는 같은 복잡도라도 방문 순서가 다르므로 최단 단계와 깊은 구조 탐색 중 필요한 결과로 선택해야 함.

- 무가중 그래프의 최단 간선 수는 BFS로 구하지만, 가중 최단 경로는 다익스트라 같은 별도 알고리즘이 필요함
- DFS는 재귀 구현이 간단하나 깊은 그래프에서 스택 초과가 발생할 수 있음
- 그래프 표현이 인접 행렬이면 탐색 비용이 `O(V^2)`로 달라질 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 그래프   | ---> | 시작정점 | ---> | 탐색구조 |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 인접목록 |      | 방문배열 |      | 결과집합 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정점 집합 | 탐색 대상 객체 또는 상태의 전체 목록임 | 지도상의 장소 |
| 간선 집합 | 정점 사이의 연결 관계이며 방향성과 가중치가 있을 수 있음 | 길 |
| 인접 표현 | 인접 리스트나 인접 행렬로 다음 방문 후보를 제공함 | 길 안내표 |
| 방문 표시 | 이미 처리한 정점을 기록해 중복 방문과 무한 순환을 막음 | 방문 도장 |
| 탐색 자료구조 | BFS는 큐, DFS는 스택 또는 재귀 호출을 사용함 | 수색 대기줄 |

> 요약: 그래프 탐색은 인접 표현에서 다음 후보를 꺼내고 방문 표시로 중복을 막으며 큐나 스택으로 순서를 제어하는 구조임.

- 방향 그래프에서는 간선 방향을 따라가므로 역방향 도달성은 별도 그래프가 필요할 수 있음
- 연결 그래프가 아니면 모든 정점을 시작점 후보로 돌며 컴포넌트를 찾아야 함
- 방문 표시 시점은 큐/스택에 넣을 때인지 꺼낼 때인지 정책을 정해야 중복 삽입을 줄일 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 초기화   | ---> | 후보추출 | ---> | 인접확장 | ---> | 결과정리 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 방문표시 |      | 큐/스택 |      | 미방문추가|     | 도달성   |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 그래프 표현, 시작 정점, 방향성, 필요한 결과가 레벨인지 경로인지 확인함
2. **초기화** - 방문 배열과 결과 저장소를 만들고 BFS는 큐, DFS는 스택 또는 재귀 호출을 준비함
3. **인접 확장** - 현재 정점의 인접 정점을 확인하고 미방문 정점을 방문 표시 후 후보 구조에 추가함
4. **출력/검증** - 방문 순서, 거리, 부모 배열, 컴포넌트 번호 등 요구한 산출물을 반환함

> 요약: 그래프 탐색 절차는 후보 자료구조에서 정점을 꺼내 인접 정점을 확장하고 방문 상태를 갱신하는 반복 흐름임.

- 최단 경로 복원이 필요하면 방문 시 부모 정점을 함께 저장해야 함
- 사이클 탐지는 단순 방문 표시 외에 재귀 스택 또는 색상 상태가 필요할 수 있음
- 대규모 그래프에서는 프론티어 크기와 메모리 사용량이 주요 운영 지표가 됨

## Ⅴ. 문제점

- **P1 방문 표시 누락**: 사이클이 있는 그래프에서 방문 상태를 기록하지 않으면 무한 반복이나 중복 처리 폭증이 발생함
- **P2 표현 방식 부적합**: 희소 그래프에 인접 행렬을 쓰면 메모리와 탐색 시간이 불필요하게 커지고, 조밀 그래프에서는 리스트 순회 비용이 커질 수 있음
- **P3 깊이·폭 편향**: BFS는 넓은 층에서 큐가 급증하고 DFS는 깊은 경로에서 재귀 스택 초과가 발생할 수 있음

> 요약: 그래프 탐색의 핵심 위험은 중복 방문, 표현 방식, 그래프 폭과 깊이에 따른 자원 사용임.

## Ⅵ. 개선방안

- **P1 대응**: 후보 구조에 넣는 시점에 방문 표시를 수행하고, 방향 그래프의 상태 색상 체계를 적용함 (확인: 사이클 포함 테스트)
- **P2 대응**: 정점 수와 간선 밀도에 따라 인접 리스트, 압축 희소 행렬, 비트셋 행렬을 선택함 (확인: 메모리 사용량과 `V/E` 비율)
- **P3 대응**: BFS는 레벨별 프론티어 제한, DFS는 반복 구현과 깊이 제한을 적용함 (확인: 최대 큐 크기와 최대 스택 깊이)

> 요약: 그래프 탐색 개선은 방문 상태를 엄격히 관리하고 그래프 밀도와 자원 한도에 맞게 표현과 구현을 선택하는 것임.

## Ⅶ. 전망

- **향후 발전 방향**: 소셜 그래프, 지식 그래프, 네트워크 분석에서는 단일 머신 탐색을 넘어 병렬 BFS, 분산 그래프 처리, 스트리밍 탐색이 중요해짐
- **기술사적 판단**: BFS/DFS를 복잡도 표로만 비교하지 말고 산출물, 그래프 표현, 폭·깊이 자원 요구를 기준으로 선택해야 함
- **기술사 제언**: 답안에서는 `그래프 표현 -> 방문 표시 -> 큐/스택 -> 결과` 흐름을 제시하면 구현과 판단이 함께 드러남

> 요약: 그래프 탐색은 관계 데이터 처리의 기본이며, 방문 순서와 표현 방식 선택이 결과 품질을 결정함.
