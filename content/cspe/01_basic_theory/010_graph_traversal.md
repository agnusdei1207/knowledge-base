## 미리 알고가기

- 정점과 간선: 그래프를 구성하는 노드와 연결 관계임
- 인접 리스트: 각 정점의 이웃 정점을 저장하는 표현 방식임
- 방문 표시: 중복 방문과 순환 탐색을 막기 위한 상태 기록임
- 무가중치 최단 경로: 간선마다 비용 차이가 없을 때 시작 정점에서 목표 정점까지 거치는 간선 수가 가장 적은 경로임
- 위상 정렬: 방향 그래프에서 선후 관계가 어긋나지 않도록 정점을 나열하는 방식임

## Ⅰ. 개요

- **정의/개념**: 그래프 탐색은 시작 정점에서 간선을 따라 정점을 체계적으로 방문해 도달 가능성, 경로, 구조 정보를 얻는 알고리즘이며, 후보 정점을 처리하는 방식에 따라 너비 우선 탐색과 깊이 우선 탐색으로 구분됨
- **배경/필요성**: 네트워크, 의존성, 상태 공간처럼 대상 간 연결 관계가 문제의 핵심인 경우 단순 순차 처리로는 도달 가능성, 경로, 순환을 판단하기 어려우므로 방문 순서를 통제하는 탐색 절차가 필요함

## Ⅱ. 특징

- BFS는 같은 거리의 정점을 층별로 확장하므로 간선 비용이 모두 같을 때 최소 간선 수 경로를 찾는 데 강함
- DFS는 한 경로를 끝까지 파고들기 때문에 구조적 성질 분석과 백트래킹 문제에 적합함
- 인접 리스트를 쓰면 BFS와 DFS는 모두 정점과 간선을 한 번씩 확인하므로 시간복잡도는 $O(V+E)$임
- 다만 BFS는 거리 순서의 결과를 만들고 DFS는 경로 깊이와 구조 분석에 맞아 중간 결과의 의미가 다름

## Ⅲ. 종류 및 비교

| 판단 기준 | BFS | DFS |
|:---|:---|:---|
| 자료구조 | 큐 | 스택 또는 재귀 |
| 탐색 방향 | 층별 확산 | 경로 우선 하강 |
| 주요 활용 | 최소 간선 수 경로 탐색 | 순환 탐지와 선후 관계 분석 |
| 메모리 특성 | 폭이 넓을수록 큐 증가 | 깊이가 깊을수록 스택 증가 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시작 정점 | 탐색 기준점이며 연결 컴포넌트 탐색 범위를 정함 |
| frontier | 다음 방문 후보 집합이며 BFS는 큐, DFS는 스택으로 관리함 |
| 방문 배열 | 이미 처리한 정점을 기록하고 순환 그래프에서 필수임 |
| 인접 정보 | 이웃 정점 목록 또는 행렬이며 자료구조에 따라 상수 비용이 달라짐 |

```text
+-----------+     +----------------+     +-----------+     +-----------+
| 시작 정점    | --> | frontier 관리    | --> | 방문 체크    | --> | 인접 정점 확장 |
+-----------+     +----------------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 시작등록 | --> | 후보추출 | --> | 이웃확장 | --> | 방문완료 |
+----------+     +----------+     +----------+     +----------+
```

1. **시작등록**: 시작 정점을 frontier에 넣고 방문 표시함
2. **후보추출**: BFS는 먼저 들어온 정점, DFS는 마지막 정점을 꺼냄
3. **이웃확장**: 아직 방문하지 않은 이웃을 frontier에 추가함
4. **방문완료**: 더 이상 후보가 없을 때 탐색을 종료함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 방문 표시 시점이 늦어 추출 후 방문 처리하면 같은 정점이 중복 삽입될 수 있음
   - 해결방안: frontier에 넣는 순간 방문 표시하고 중복 삽입 횟수로 검증함
2. 문제: BFS에서 폭이 큰 그래프가 메모리를 압박해 동일 레벨 정점이 폭증하면 큐가 커짐
   - 해결방안: 깊이 제한, 양방향 탐색, 문제 축소 전략을 적용하고 큐 최대 길이로 검증함
3. 문제: DFS 재귀가 깊이 한계를 넘어 편향 그래프에서 호출 깊이가 시스템 제한을 초과할 수 있음
   - 해결방안: 명시적 스택 기반 반복 DFS로 전환하고 최대 깊이 테스트로 검증함

## Ⅶ. 적용 사례

- 네트워크 경로 분석에서는 BFS로 최소 홉 경로를 찾으며, 탐색 시간과 홉 수 정확도로 결과를 확인함
- 소스 코드 의존성 검사에서는 DFS로 순환 참조를 탐지하며, 사이클 검출률과 분석 시간으로 결과를 확인함
- 게임 맵 탐색에서는 최단 이동이 필요하면 BFS를, 모든 경로 검사가 필요하면 DFS를 쓰며 경로 길이와 메모리 사용량으로 결과를 확인함

## Ⅷ. 결론

그래프 탐색은 같은 복잡도라도 얻는 결과가 다르므로, 거리 보장이 필요하면 BFS를 쓰고 구조 분석이나 가지치기가 중요하면 DFS를 써야 함.
