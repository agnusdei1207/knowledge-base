## 미리 알고가기

- 모듈러 연산: 정수 나눗셈의 나머지 범위에서 덧셈·곱셈·거듭제곱을 수행하는 연산임
- 오일러 피 함수 $\phi(n)$: $n$과 서로소인 양의 정수 개수를 나타내는 함수임
- 일방향 함수: 순방향 계산은 가능하지만 역산에는 현실적 계산 한도를 넘는 비용이 필요한 함수임
- 트랩도어: 비밀 정보를 알면 역연산을 계산할 수 있지만 모르면 계산이 어려운 수학적 구조임
- 이산 로그 문제: 거듭제곱 결과에서 지수를 찾기 어려운 문제임
- OAEP: RSA 평문에 난수 패딩을 적용해 같은 평문의 암호문을 달리하고 선택 암호문 공격 저항성을 제공하는 방식임
- PQC(Post-Quantum Cryptography): 양자 알고리즘 공격을 고려해 설계한 공개키 암호 체계임

## 작성 근거(검토용)

- 개요는 난제와 공개키 기능을 연결해 암호 수학의 실무 목적을 드러냄
- 특징은 소인수분해 비대칭성, 공개/개인키 역할, 모듈러 연산, 하이브리드 사용을 RSA 판단 기준으로 선정함
- Ⅲ은 RSA·DH·ECC의 기반 난제와 용도 차이를 비교해 암호 방식 선택 기준을 제시함
- 구조 도식은 공개키·개인키와 암·복호화 수식을 RSA 원리의 최소 구조로 제시함
- 패딩과 PQC 전환은 수학적 안전성이 구현·운영에서 깨지는 대표 조건임

## Ⅰ. 개요

- **정의/개념**: 암호 수학은 소인수분해·이산 로그 같은 난제를 이용해 공개키 암호와 전자서명을 구성하는 이론임
- **배경/필요성**: 공개망에서 기밀성과 인증을 확보하기 위해 공개키와 개인키를 분리한 암호 구조가 필요함

## Ⅱ. 특징

- RSA는 큰 두 소수의 곱은 다항 시간에 계산되지만 소인수분해에는 알려진 고전 다항 시간 알고리즘이 없다는 비대칭성을 이용함
- 공개키는 암호화·서명 검증에, 개인키는 복호화·서명에 사용함
- 모듈러 거듭제곱과 역원을 사용해 일방향 함수의 트랩도어 관계를 구성함
- RSA는 대칭키 암호보다 큰 정수 모듈러 연산 비용이 크므로 대용량 본문보다 키 전달·서명·하이브리드 암호에 사용함

## Ⅲ. 종류 및 비교

| 판단 기준 | RSA | DH | ECC |
|:---|:---|:---|:---|
| 기반 난제 | 큰 정수 소인수분해 | 유한체 이산 로그 | 타원곡선 이산 로그 |
| 주요 용도 | 암호화, 서명 | 세션키 합의 | ECDSA 서명, ECDH 키 합의 |
| 핵심 연산 | 큰 정수 모듈러 거듭제곱 | 유한체 모듈러 거듭제곱 | 타원곡선 스칼라 곱셈 |
| 공개 매개변수 | 모듈러스 $n$·공개 지수 $e$ | 소수 $p$·생성원 $g$ | 타원곡선 매개변수·기준점 |

> 요약: RSA는 소인수분해, DH는 유한체 이산 로그, ECC는 타원곡선 이산 로그 난제를 기반으로 공개키 기능을 제공함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 소수 $p, q$ | 외부에 노출하면 안 되는 RSA 개인 구성값임 |
| 모듈러스 $n$ | $p \times q$로 만든 공개 연산 공간임 |
| 공개 지수 $e$ | 암호화와 서명 검증에 쓰는 공개값임 |
| 개인 지수 $d$ | $ed \equiv 1 \pmod{\phi(n)}$을 만족하는 비밀값임 |
| 패딩 | 평문 구조 노출과 반복 암호문 생성을 방지하는 무작위화 절차임 |

```text
[ RSA 구조 ]
공개키 = (e, n)
개인키 = (d, n)
암호화: C = M^e mod n
복호화: M = C^d mod n
```

> 요약: RSA는 같은 모듈러스에서 공개 지수와 개인 지수가 서로 역연산 관계를 이루게 함.

## Ⅴ. 원리 및 절차 흐름도

```text
[키 생성] 난수 소수 p, q -> n·phi(n) 계산 -> 공개키 (e, n)·개인키 (d, n)
[암호화] 평문 -> 공개키 암호화 -> 암호문 -> 개인키 복호화 -> 평문
[서명]   메시지 -> 개인키 서명 -> 서명값 -> 공개키 검증 -> 검증 결과
```

1. **소수 생성**: 보안 강도에 맞는 비트 길이의 난수 소수 $p, q$를 생성함
2. **키 계산**: $n$, $\phi(n)$, $e$, $d$의 관계를 계산함
3. **암·복호화**: 공개키로 평문을 암호화하고 개인키로 암호문을 복호화함
4. **서명·검증**: 개인키로 메시지에 서명하고 공개키로 서명값을 검증함

> 요약: RSA는 암호화에서 공개키·개인키 순서로, 전자서명에서 개인키·공개키 순서로 연산함.

## Ⅵ. 실무 사례

1. RSA 암호화 모듈은 OAEP 패딩을 적용하고 패딩 오류 응답 일관성·난수 생성기 검정 결과로 검증함
2. 장기 인증서·서명 자산은 PQC 전환 계획을 수립하고 취약 자산 수·인증서 교체율로 검증함

## Ⅶ. 결론

- 암호 수학은 기반 난제에 맞는 키 길이·패딩을 적용하고 양자 위협에 대비해 키·알고리즘 전환 주기를 관리해야 함
