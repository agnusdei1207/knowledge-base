## 미리 알고가기

- 모듈러 연산: 정수 나눗셈의 나머지 범위에서 덧셈·곱셈·거듭제곱을 수행하는 연산임
- 오일러 피 함수 $\phi(n)$: $1$ 이상 $n$ 이하 정수 중 $n$과 서로소인 개수를 나타내는 함수임
- 일방향 함수·트랩도어: 순방향 계산은 쉽지만 비밀 정보 없이는 역산이 어려운 수학적 구조임
- 이산 로그 문제: 거듭제곱 결과에서 지수를 찾기 어려운 문제임
- 난수 패딩(OAEP): RSA 평문에 난수를 섞어 같은 평문의 암호문을 달리하는 방식임
- 양자내성암호(PQC): 양자 알고리즘 공격을 고려해 설계한 공개키 암호 체계임
- 디피-헬먼 키 합의(DH): 유한체의 이산 로그 문제를 기반으로 공유 비밀을 합의하는 방식임
- 타원곡선 암호(ECC): 타원곡선 이산 로그 문제를 기반으로 서명·키 합의를 수행하는 방식임
- RSA 수식 기호: $n$은 모듈러스, $e$·$d$는 공개·개인 지수, $M$·$C$는 평문·암호문임
- 패딩 오라클: 패딩 오류 응답 차이로 평문 정보를 추론하는 공격임

## 작성 근거(검토용)

- 개요는 난제와 공개키 기능을 연결해 암호 수학의 실무 목적을 드러냄
- 특징은 소인수분해 비대칭성, 공개/개인키 역할, 모듈러 연산, 하이브리드 사용을 RSA 판단 기준으로 선정함
- Ⅲ은 이산 로그 문제의 정의를 먼저 제시해 복합 키워드의 개별 설명을 완성하고, RSA·DH·ECC의 기반 난제, 핵심 기능, 주요 리스크를 비교함
- 구조 도식은 공개키·개인키와 암·복호화 수식을 RSA 원리의 최소 구조로 제시함
- 패딩과 PQC 전환은 수학적 안전성이 구현·운영에서 깨지는 대표 조건임

## Ⅰ. 개요

- **정의/개념**: 암호 수학은 소인수분해·이산 로그 같은 난제를 이용해 공개키 암호와 전자서명을 구성하는 이론임
- **배경/필요성**: 공개망에서 기밀성과 인증을 확보하기 위해 공개키와 개인키를 분리한 암호 구조가 필요함

## Ⅱ. 특징

- 큰 소수의 곱셈은 다항 시간에 계산되지만 소인수분해에는 알려진 고전 다항 시간 알고리즘이 없어 RSA는 이 비대칭성을 이용함
- 공개키는 암호화·서명 검증에, 개인키는 복호화·서명에 사용함
- 모듈러 거듭제곱과 역원을 사용해 일방향 함수의 트랩도어 관계를 구성함
- RSA는 대칭키 암호보다 큰 정수 모듈러 연산 비용이 크므로 대용량 본문보다 키 전달·서명·하이브리드 암호에 사용함

## Ⅲ. 종류 및 비교

- 이산 로그 문제는 유한체나 타원곡선에서 거듭제곱 결과로부터 원래 지수를 구하는 문제임. 정방향 계산과 달리 역산에 알려진 다항 시간 알고리즘이 없어 디피-헬먼·ECC 안전성의 근거가 됨

| 판단 기준 | RSA | DH | ECC |
|:---|:---|:---|:---|
| 기반 난제 | 큰 정수 소인수분해 | 유한체 이산 로그 | 타원곡선 이산 로그 |
| 핵심 기능 | 암호화·서명 | 키 합의 | 서명·키 합의 |
| 주요 리스크 | 패딩 오라클 | 인증 부재 중간자 공격 | 곡선 검증 오류 |

> 요약: RSA는 소인수분해, DH는 유한체 이산 로그, ECC는 타원곡선 이산 로그 난제를 기반으로 공개키 기능을 제공함.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 소수 $p, q$ | 외부에 공개하지 않는 개인 구성값 |
| 모듈러스 $n$ | $p \times q$로 만든 공개 연산 공간 |
| 공개 지수 $e$ | 암호화·서명 검증 공개값 |
| 개인 지수 $d$ | $ed \equiv 1 \pmod{\phi(n)}$인 비밀값 |
| 패딩 | 암호화·서명 입력을 RSA 모듈러스 연산에 맞게 인코딩하는 절차 |

```text
[ RSA 구조 ]
공개키 = (e, n)
개인키 = (d, n)
암호화: C = M^e mod n
복호화: M = C^d mod n
```

> 요약: RSA는 공개·개인 지수의 모듈러 역원 관계로 암·복호화 연산을 반전하고 패딩 규격으로 암호화·서명 입력을 인코딩함.

## Ⅴ. 원리 및 절차 흐름도

```text
[키 생성] 난수 소수 p, q -> n·phi(n) 계산 -> 공개키 (e, n)·개인키 (d, n)
[암호화] 평문 -> 공개키 암호화 -> 암호문 -> 개인키 복호화 -> 평문
[서명]   메시지 -> 개인키 서명 -> 서명값 -> 공개키 검증 -> 검증 결과
```

1. **소수 생성**: 보안 강도에 맞는 비트 길이의 난수 소수 $p, q$를 생성함
2. **키 계산**: $n$, $\phi(n)$, $e$, $d$의 관계를 계산함
3. **암·복호화**: OAEP로 인코딩한 평문을 공개키로 암호화하고 개인키로 복호화함
4. **서명·검증**: 메시지 해시를 서명 형식으로 인코딩해 개인키로 서명하고 공개키로 검증함

> 요약: RSA는 암호화에서 공개키·개인키 순서로, 전자서명에서 개인키·공개키 순서로 연산함.

## Ⅵ. 실무 사례

1. RSA 암호화 모듈은 OAEP 패딩을 적용하고 패딩 오류 응답 일관성·난수 생성기 검정 결과로 검증함
2. 장기 인증서·서명 자산은 PQC 전환 계획을 수립하고 취약 자산 수·인증서 교체율로 검증함

## Ⅶ. 결론

- RSA는 소인수분해의 어려움으로 공개키 암호를 구현하며, 표준 패딩 적용과 양자내성 암호 전환이 필요함
- 대용량 데이터는 RSA로 직접 암호화하지 말고 하이브리드 암호를 사용하며, 키·패딩·인증서 자산을 PQC 전환 목록으로 관리해야 함
