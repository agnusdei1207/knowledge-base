# 암호 수학 - 이산대수·RSA 원리 (Cryptography Mathematics)

## 1. 개요

- **정의/개념**: 암호 수학은 모듈러 연산, 소인수분해, 이산대수 문제 같은 계산 난제를 기반으로 암호화, 서명, 키 교환의 안전성을 설명하는 수학적 기반이다.
- **배경/필요성**: 암호 시스템은 알고리즘을 숨기는 것이 아니라 공개된 수학 문제의 계산 어려움에 의존하므로, 기반 난제와 연산 구조를 이해해야 안전한 선택이 가능하다.

RSA의 핵심은 큰 합성수의 소인수분해가 어렵다는 가정 위에서 공개키 암호와 전자서명을 구현한다는 점이다.

## 2. 특징 및 비교

| 구분 | RSA | 이산대수 기반 | 대칭키 암호 |
|---|---|---|---|
| 기반 문제 | 소인수분해 | 이산대수, 타원곡선 이산대수 | 혼돈·확산 구조 |
| 키 구조 | 공개키/개인키 | 공개키/개인키 | 공유 비밀키 |
| 강점 | 서명·키 교환에 활용 | 짧은 키로 효율 가능 | 빠른 대량 암호화 |
| 한계 | 느림, 큰 키 | 파라미터 선택 중요 | 키 분배 문제 |

선택 기준은 안전성 가정, 키 길이, 연산 비용, 표준 준수, 양자 위협이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Modular Arithmetic | 나머지 연산 기반 계산 | 폐쇄적 연산 공간 |
| Prime Numbers | RSA 키 생성 기초 | 큰 소수 |
| Euler/Phi Function | 개인키 계산 기반 | `phi(n)` |
| Public Key | 암호화·검증에 공개 | `(n,e)` |
| Private Key | 복호화·서명에 사용 | `d` 보호 |

```text
큰 소수 p,q -> n=pq -> 공개키/개인키 생성 -> 암호화/서명 -> 복호화/검증
```

공개키는 공개되어도 되지만 개인키와 소수 인자는 보호되어야 하며, 이 경계가 암호 시스템의 보안 구조를 만든다.

## 4. 문제점 및 개선방안

1. **키 길이·파라미터 부적절**
   - 작은 키나 약한 난수로 생성된 키는 공격에 취약하다.
   - **개선방안**: 표준 권고 키 길이, 안전한 난수 생성기, 검증된 라이브러리를 사용한다.

2. **패딩 없는 RSA**
   - textbook RSA는 결정적이고 다양한 공격에 취약하다.
   - **개선방안**: OAEP, PSS 같은 안전한 padding scheme을 적용한다.

3. **양자 컴퓨팅 위협**
   - Shor 알고리즘은 충분한 규모의 양자 컴퓨터에서 RSA 기반 난제를 약화시킨다.
   - **개선방안**: PQC 전환 계획과 crypto agility를 준비한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| TLS 인증 | RSA/ECDSA 서명으로 서버 인증 | 인증서 유효성 |
| 전자서명 | 개인키로 서명하고 공개키로 검증 | 위변조 검출 |
| 키 교환 설계 | 공개키로 세션키 교환 또는 인증 수행 | handshake 비용 |

## 6. 결론

암호 수학은 공개된 알고리즘의 안전성을 계산 난제로 설명하는 기반이다. RSA 수식만 나열하지 말고 기반 난제, 키 생성, 연산 방향, padding, 양자 위협까지 연결해야 안전한 암호 시스템 판단이 가능하다.
