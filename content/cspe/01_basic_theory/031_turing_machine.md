## Ⅰ. 개요
- **정의**: 무한 테이프·헤드·상태전이로 구성된 추상 계산 모델
- **배경/필요성**: 알고리즘으로 풀 수 있는 문제의 범위를 형식적으로 정의할 수단이 필요함
- **비유**: 무한히 긴 줄자 위를 왔다 갔다 하며 칸에 글자를 쓰고 지우는 로봇 팔

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계산 가능성의 형식적 정의 이해 | 7-튜플 구성과 상태전이 함수 | 결정적/비결정적 구분, 정지 문제 언급 |

> 요약: 알고리즘적 풀이 가능 여부를 판별하는 형식 계산 모델임

## Ⅱ. 구성요소
```text
  +--------+     읽기/쓰기     +-----------+
  | 헤드   |<--------------->| 무한 테이프 |
  +--------+                  +-----------+
      |                        ... |a|b|c| ...
      | 상태전이 참조
      v
  +------------------+
  | 상태전이 함수     |
  | (현재상태, 입력)  |
  |  -> (다음상태,    |
  |     출력, 이동)   |
  +------------------+
      |
      v
  +------------------+
  | 유한 상태 집합    |
  | (시작/수락/거부)  |
  +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 무한 테이프 | 셀 단위로 기호를 저장하는 무한 길이 저장매체 | 끝없는 줄자 |
| 헤드 | 테이프의 현재 셀을 읽고 쓰며 좌우로 이동하는 장치 | 줄자 위 로봇 손가락 |
| 상태전이 함수 | (현재 상태, 입력 기호) → (다음 상태, 출력 기호, 이동 방향) 매핑 | 업무 매뉴얼의 조건표 |
| 유한 상태 집합 | 시작·수락·거부 상태를 포함하는 유한 개수의 상태 모음 | 신호등의 색 집합 |

> 요약: 테이프·헤드·상태전이 함수·상태 집합 4요소가 계산 과정을 형식화함

## Ⅲ. 절차
```text
  초기화          읽기           전이            종료판정
  (테이프 셋업)  (헤드가 읽음)  (함수 적용)     (수락/거부)
   |              |              |               |
   +---입력------>+---기호------->+---상태변경---->+
  테이프 로드    현재 셀 참조   쓰기+이동 수행  정지 상태 도달
```
- 1단계: 입력 문자열을 테이프에 기록하고 헤드를 시작 위치에 배치함
- 2단계: 헤드가 현재 셀의 기호를 읽고 현재 상태와 함께 전이 함수에 전달함
- 3단계: 전이 함수 결과에 따라 셀에 기호를 쓰고 헤드를 좌/우로 이동하며 상태를 갱신함
- 4단계: 수락 또는 거부 상태에 도달하면 정지하고 결과를 출력함

> 요약: 읽기 → 전이 → 쓰기/이동을 수락·거부 상태 도달까지 반복하는 절차임

## Ⅳ. 문제점
- 정지 문제: 임의 프로그램의 정지 여부를 판별하는 일반 알고리즘이 존재하지 않음
- 공간 비효율: 무한 테이프 가정은 실제 유한 메모리 환경과 괴리가 있음
- 속도 추상화: 단일 테이프 모델의 시간 복잡도가 실제 컴퓨터 성능과 직접 대응하지 않음

> 요약: 정지 불가판별·무한 자원 가정·속도 괴리가 실용 적용의 한계임

## Ⅴ. 개선방안
1. 단기: 다중 테이프·비결정적 모델로 시간 복잡도 분석 정밀화
2. 중기: 유한 오토마타·푸시다운 오토마타 등 제한 모델 계층화로 실용 문제 분류 체계 구축
3. 장기: 양자 튜링 머신 등 확장 모델로 계산 가능성 경계 재정의

> 요약: 모델 확장과 계층화를 통해 이론과 실제 간 간극을 줄여가는 방향임

## Ⅵ. 전망
- 발전 방향: 양자 컴퓨팅·DNA 컴퓨팅 등 비전통 계산 모델의 이론적 기반으로 활용 확대
- 기술사적 판단: 계산 복잡도 이론(P vs NP 등)의 근간으로서 지속적 중요성을 가짐
- 기술사 제언: 계산 가능성과 복잡도 구분을 명확히 하여 문제 분류 역량을 확보할 필요
