## 미리 알고가기

- `O(g(n))`: 충분히 큰 입력에서 `f(n)`이 `g(n)`의 상수배 이하로 증가한다는 상한 표기임
- `Omega(g(n))`: 충분히 큰 입력에서 `f(n)`이 `g(n)`의 상수배 이상이라는 하한 표기임
- `Theta(g(n))`: 상한과 하한이 같은 증가율로 묶이는 정확한 차수 표기임
- `c`, `n0`: 상수배와 "이 입력 크기 이후"를 나타내는 증명용 기준값임

## Ⅰ. 개요

- **정의**: 알고리즘 비용의 점근적 상한을 나타내는 표기법임
- **배경/필요성**: 입력 규모가 커질 때 지배적인 증가율만 비교해야 하드웨어·언어 차이에 덜 흔들리는 알고리즘 선택이 가능함
- **비유**: 빅오는 "아무리 커져도 이 정도 속도 이상으로는 늘지 않는다"는 비용 상한선임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 점근 표기와 복잡도 도출 역량 확인 | 상한 의미, 최고차항, 상수 제거, `O/Omega/Theta` 구분 | 정확한 실행시간 단정, 하한·정확차수 혼동 |

> 요약: 빅오는 실행 시간을 재는 초 단위가 아니라 입력 증가에 따른 비용 상한을 표현하는 수학적 약속임.

## Ⅱ. 특징/비교

| 판단 기준 | Big-O | Theta / Omega |
|:---|:---|:---|
| 의미 | 점근적 상한, 최악 비용 설명에 자주 사용 | 정확한 차수 또는 하한 설명 |
| 답안 역할 | 알고리즘이 감당해야 할 최대 증가율 제시 | 최선·평균·정확 범위를 보완 |
| 주의점 | 느슨한 상한도 참이므로 과도하게 큰 표기 가능 | 조건을 만족하지 않으면 잘못된 차수 표기 |

> 요약: Big-O는 상한 판단에 유용하지만, 정확한 성능 판단에는 `Theta`, `Omega`, 입력 조건을 함께 봐야 함.

- `3n^2 + 5n + 2`는 큰 입력에서 `n^2` 항이 지배하므로 `O(n^2)`로 정리함
- `O(1)`, `O(log n)`, `O(n)`, `O(n log n)`, `O(n^2)`는 증가율 차이를 직관적으로 비교하는 대표 계층임
- 빅오 표기는 알고리즘 선택을 단순화하지만, 모든 운영 성능을 설명하는 지표는 아님

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 비용함수 | ---> | 지배항   | ---> | O(g(n)) |
| f(n)     |      | g(n)    |      | 상한표기 |
+----------+      +----------+      +----------+
                         |
                         v
                   +----------+
                   | c, n0    |
                   +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 비용 함수 `f(n)` | 실제 연산 횟수를 입력 크기의 함수로 표현한 값임 | 실제 영수증 금액 |
| 지배 함수 `g(n)` | 큰 입력에서 증가율을 대표하는 최고차 함수임 | 가장 큰 비용 항목 |
| 상수 `c` | `g(n)`에 곱해 `f(n)`을 덮는 허용 배율임 | 안전 여유분 |
| 기준 입력 `n0` | 상한 관계가 성립하기 시작하는 입력 크기임 | 적용 시작선 |

> 요약: 빅오는 `f(n) <= c*g(n)`이 충분히 큰 입력에서 성립함을 보이는 상한 표기임.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 연산선정 | ---> | 함수도출 | ---> | 지배항선택 | ---> | 상한검증 |
+----------+      +----------+      +----------+      +----------+
```

1. **연산 선정**: 반복문 내부 비교·대입처럼 실행 횟수를 대표하는 기본 연산을 정함
2. **함수 도출**: 반복 횟수와 재귀 호출을 합산해 `f(n)`을 계산함
3. **지배항 선택**: 하위 항과 계수를 제거하고 큰 입력에서 지배하는 `g(n)`을 선택함
4. **상한 검증**: 적절한 `c`, `n0`가 존재하는지 확인하고 `O(g(n))`로 표기함

> 요약: 빅오 도출은 연산 횟수 함수에서 지배항을 선택하고 상한 관계를 확인하는 과정임.

## Ⅴ. 문제점

- **P1 느슨한 상한 오용**: `O(n)` 알고리즘도 수학적으로는 `O(n^2)`에 포함되므로, 가장 타이트한 상한을 쓰지 않으면 비교력이 떨어짐
- **P2 상수·하위항 은닉**: `O(n)` 두 알고리즘의 실제 연산 수가 `2n`과 `100n`이면 작은 입력에서 체감 지연이 달라짐
- **P3 조건 미기재**: 평균 `O(1)` 해시 탐색처럼 입력 분포와 충돌 조건이 필요한 표기를 보장 성능처럼 쓸 수 있음

> 요약: Big-O는 타이트한 상한과 적용 조건을 함께 써야 채점자가 정확한 이해로 판단함.

## Ⅵ. 개선방안

1. **단기**: 가능한 한 타이트한 상한을 쓰고 `O`, `Theta`, `Omega`의 의미를 구분해 표기함
2. **중기**: 입력 범위가 작은 업무는 실제 연산 수, 상수 계수, 벤치마크 결과를 함께 확인함
3. **장기**: 알고리즘 표준 문서에 평균·최악 조건, 데이터 분포, 병목 지표를 같이 기록함

- **P1 대응**: `O(n^2)`처럼 느슨한 표기 대신 `O(n)` 또는 `Theta(n)` 가능 여부를 검토함 (확인: 상한·하한 증명)
- **P2 대응**: 구현 후보별 벤치마크로 상수 계수 영향을 검증함 (확인: 대표 입력 p95 지연)
- **P3 대응**: 평균·최악 조건과 전제 조건을 표기 옆에 명시함 (확인: 충돌률, 정렬 여부, 입력 분포)

> 요약: Big-O는 수학 표기와 운영 검증을 결합할 때 실무 선택 기준으로 작동함.

## Ⅶ. 전망

- 대규모 데이터와 AI 워크로드에서는 시간복잡도뿐 아니라 메모리 대역폭, 통신량, 병렬화 한계를 함께 표기하는 경향이 커짐
- 기술사는 Big-O를 암기식 분류가 아니라 요구사항 대비 알고리즘 후보를 거르는 1차 필터로 활용해야 함
- 답안에서는 표기 정의, 도출 과정, 한계를 짧게 연결해 "알고리즘을 선택할 수 있는 사람"이라는 인상을 줘야 함
