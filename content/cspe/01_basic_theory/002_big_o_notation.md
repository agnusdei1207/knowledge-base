## 미리 알고가기

- 점근적 분석: 입력 크기 $n$이 충분히 커질 때 알고리즘 자원 소모량의 증가 추이를 분석하는 방법임
- 상한(Upper Bound): 충분히 큰 입력에서 비용 함수가 기준 함수의 상수배를 넘지 않도록 묶는 한계임
- 최고차항: 비용 함수에서 입력값 $n$이 증가함에 따라 결과값에 가장 큰 영향을 주는 지배적인 항임

## Ⅰ. 개요

- **정의/개념**: 빅오 표기법은 알고리즘의 복잡도 함수에서 입력 $n$이 증가함에 따라 비용이 늘어나는 점근적 상한을 $O(f(n))$으로 추상화하여 확장성의 한계를 표현하는 표기법임
- **배경/필요성**: 실행 환경에 따라 달라지는 절대 처리 시간만으로는 알고리즘을 비교하기 어려우므로, 대규모 입력에서 지연 시간과 자원 사용량이 어떤 차수로 증가하는지 비교할 척도가 필요함

## Ⅱ. 특징

- 상수 계수와 낮은 차수 항을 제거하고 지배적인 증가 항만 남겨 자원 소모 증가율을 드러냄
- 분석 대상 비용 함수가 충분히 큰 입력에서 기준 함수의 상수배를 넘지 않음을 보여 보수적 자원 산정 근거를 제공함
- 구체적인 실행 상수 비용은 표기에 드러나지 않으므로, 복잡도 차수가 동일한 알고리즘 간의 비교에서는 실제 벤치마크 지표를 병행 확인해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 빅오 ($O$) | 빅세타 ($\Theta$) | 빅오메가 ($\Omega$) |
|:---|:---|:---|:---|
| **비교 목적** | 점근적 상한 확인 | 점근적 tight bound 확인 | 점근적 하한 확인 |
| **수학적 의미** | 충분히 큰 $n$에서 $T(n) \le c \cdot f(n)$ 만족 | 충분히 큰 $n$에서 $c_1 \cdot f(n) \le T(n) \le c_2 \cdot f(n)$ 만족 | 충분히 큰 $n$에서 $T(n) \ge c \cdot f(n)$ 만족 |
| **실무적 관점** | 자원 증가 상한의 보수적 기준 | 실제 증가 차수의 정확한 표현 | 최소 증가 한계 증명 |

> 요약: 실무에서는 최악 시간복잡도를 빅오($O$)로 표현해 대규모 입력에서의 자원 증가 상한을 보수적으로 판단함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비용 함수 $T(n)$ | 알고리즘을 수행하는 데 필요한 실제 연산 횟수나 메모리 사용량을 나타내는 함수임 |
| 기준 함수 $f(n)$ | 상한선의 모양을 결정하는 핵심 차수(예: $n$, $\log n$, $n^2$)를 담은 함수임 |
| 상수 $c$ | 특정 입력 크기 이후부터 $T(n)$이 상한선 아래에 있음을 보장하기 위해 도입된 양의 실수임 |
| 기준점 $n_0$ | 점근적 상한 관계가 어긋나지 않고 성립하기 시작하는 최소 입력 크기 임계치임 |

```text
[ 빅오 성립 관계 ]
    비용
     ^           / c * f(n) (상한선)
     |          /
     |         /  T(n) (실제비용)
     |        /
     |       /
     +------|------------> 입력(n)
           n0 (기준점)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 연산 식 도출  | --> | 지배항 추출   | --> | 계수 제거    | --> | 상한 확정    |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **식 도출** — 코드의 반복문과 재귀 깊이를 분석하여 입력 $n$에 대한 전체 연산 수 함수 $T(n)$을 정의함
2. **항 추출** — 입력이 충분히 클 때 전체 비용에 기여도가 낮은 하위 차수 항들을 제거하고 지배항만 남김
3. **계수 제거** — 점근 차수는 상수 계수와 무관하므로 지배항 앞의 상수 계수를 생략함
4. **상한 확정** — 남은 함수를 $O(f(n))$ 기호 안에 담아 알고리즘의 확장 한계를 최종적으로 확정함

## Ⅵ. 실무 적용 및 유의점

1. 후보 알고리즘은 빅오 차수로 먼저 좁히되, 입력 규모가 작거나 캐시 미스와 I/O 대기 같은 상수 비용이 큰 경우에는 임계 지연 시간과 프로파일링 지표로 교차 검증해야 함
2. 해시 테이블은 평균 $O(1)$이더라도 충돌이 집중되면 최악 $O(n)$까지 퇴화할 수 있으므로, 해시 함수와 로드 팩터와 리사이징 정책을 관리하고 충돌률과 p99 조회 지연으로 확인해야 함

## Ⅶ. 결론

- 빅오 표기법은 입력 증가에 따른 자원 사용 상한을 비교하는 기준이므로, 설계자는 차수와 상수 비용과 입력 분포를 함께 확인해 알고리즘 선택 근거를 제시해야 함
