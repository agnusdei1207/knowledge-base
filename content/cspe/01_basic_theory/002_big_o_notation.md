## 미리 알고가기

- 점근 표기: 입력이 충분히 커진 뒤의 증가율을 표현하는 방법임
- 지배항: 여러 항 중 입력 증가에 가장 큰 영향을 주는 항임
- 상한: 비용이 특정 함수보다 빠르게 커지지 않는다는 한계임
- $\Theta$: 상한과 하한이 같은 차수로 맞는 경우를 나타냄

## Ⅰ. 개요

- **정의/개념**: 빅오 표기법은 알고리즘 비용 함수에서 입력이 커질 때 지배항만 남겨 증가율의 상한을 $O(f(n))$으로 표현하는 방법임
- **배경/필요성**: 장비와 언어가 달라도 알고리즘의 확장성은 비교해야 함. 빅오는 작은 상수 차이를 걷어내고 입력 증가에 따른 구조적 차이를 보여줌

## Ⅱ. 특징

- 절대 실행시간이 아니라 입력 증가율을 나타내므로 알고리즘 후보를 빠르게 비교할 수 있음
- 상수항과 낮은 차수 항을 버리므로 큰 입력에서 지배적인 비용을 중심으로 판단함
- 주로 최악 경우 상한을 설명하는 데 쓰여 응답시간 한계와 용량 산정의 출발점이 됨
- 캐시, I/O, 구현 상수는 빅오에 드러나지 않으므로 실제 성능 측정과 함께 써야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | $O$ | $\Theta$ | $\Omega$ |
|:---|:---|:---|:---|
| 의미 | 비용 증가율의 상한 | 비용 증가율의 정확한 차수 | 비용 증가율의 하한 |
| 답하는 질문 | 어디까지 느려질 수 있는가 | 실제로 어느 속도로 커지는가 | 이보다 더 줄일 수 없는가 |
| 주 사용 | 최악 성능 설명 | 알고리즘 차수 확정 | 문제의 이론적 한계 설명 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비용 함수 $T(n)$ | 입력 크기에 따른 실제 연산 수를 표현한 함수임 |
| 후보 함수 $f(n)$ | 상한으로 비교할 증가율 함수임 |
| 상수 $c$ | $T(n)$을 $f(n)$의 상수배 안에 넣기 위한 값임 |
| 기준 입력 $n_0$ | 충분히 큰 입력부터 상한 관계가 성립함을 나타내는 시작점임 |

```text
+------------+     +----------+     +-------------+
| T(n) 작성 | --> | 지배항 선택 | --> | O(f(n)) 확정 |
+------------+     +----------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 연산 수 계산 | --> | 낮은 항 제거 | --> | 상수 제거 | --> | 상한 표기 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 반복문, 재귀, 자료구조 연산에서 비용 함수를 구함
2. 입력이 커질 때 영향이 작은 항을 제거함
3. 상수배를 제거하고 지배항만 남김
4. 필요한 경우 $\Theta$나 $\Omega$로 의미를 보완함

## Ⅵ. 실무 적용 및 유의점

1. 알고리즘 후보를 고를 때는 빅오로 먼저 걸러내고, 최종 선택은 실제 입력 분포와 측정 지연시간으로 확인해야 함
2. $O(1)$이나 $O(\log n)$이라는 표현만 믿지 말고 해시 충돌, 디스크 I/O, 네트워크 호출 등 표기 밖의 비용을 따로 점검해야 함

## Ⅶ. 결론

- 빅오는 입력 증가에 따른 비용 상한을 간단히 보여주는 표기이며, 실제 성능 판단에는 입력 조건과 측정 결과가 함께 필요함
