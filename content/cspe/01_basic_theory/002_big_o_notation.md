## Ⅰ. 개요
- 알고리즘의 실행 시간 상한(Upper Bound)을 나타내는 점근적 표기법임.
- 데이터 증가에 따른 성능 변화 추이를 예측하기 위한 도구임.
- [표] 출제 의도: 알고리즘 성능의 최악 상황 대비 설계 능력 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  Time |         / f(n) <= c * g(n)
       |        /
       |       /-- g(n)
       |      /
       +------------- Input (n)

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 점근적 상한 | 최악의 경우에도 넘지 않는 한계선 | 안전 속도 제한 |
| 데이터(n) | 알고리즘의 입력 데이터 수량 | 화물의 무게 |
| 증가율 | n에 따른 연산량 증가 기울기 | 가속도 정도 |

> 요약: 불필요한 세부 사항을 제외하고 성능의 척도를 단순화함.

## Ⅲ. 절차
- ASCII 흐름도
  Code Analysis -> Polynomial Eq -> Keep Max Degree -> Constant Drop

1. 코드의 루프 횟수와 재귀 깊이를 정밀하게 분석함.
2. 입력 n에 대한 실행 시간 다항식을 작성함.
3. 가장 빠르게 증가하는 최고차항만 남기고 나머지는 제거함.
4. 상수 계수를 생략하여 최종 Big-O 형태로 변환함.

> 요약: 핵심 차수를 도출하여 성능의 등급(Class)을 결정함.

## Ⅳ. 문제점
- n이 작을 경우 계수가 큰 O(n)보다 계수가 작은 O(n^2)이 빠를 수 있음.
- 최악의 상황만 고려하여 평균적인 실행 성능을 대변하지 못함.

## Ⅴ. 개선방안
- 단기: 평균 성능 분석을 위해 Big-Theta 표기법을 병행 사용함.
- 중기: 실제 데이터셋을 활용한 프로파일링으로 상수 효율 최적화함.
- 장기: 확률적 분석 기법 도입으로 기대 실행 시간 산출 필요함.

## Ⅵ. 전망
- CI/CD 파이프라인 내 '성능 예산(Performance Budget)' 개념이 도입되어 코드 커밋 단계에서 Big-O 변동을 자동 감시하는 구조가 일반화될 것임.
- 클라우드 네이티브 환경에서는 알고리즘의 비효율성이 탄소 배출과 직결되므로, '그린 알고리즘' 관점의 탄소 효율적 복잡도 분석이 CSF로 부각됨.
- 머신러닝 기반의 알고리즘 자동 선택(Auto-Algorithm Selection) 기술과 결합하여 데이터 분포에 따른 최적 점근 복잡도를 실시간으로 추론하는 방향으로 발전할 것임.
