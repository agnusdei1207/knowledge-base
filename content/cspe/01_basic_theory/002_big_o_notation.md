## 핵심 답안

빅오 표기법은 알고리즘의 시간 또는 공간 비용이 입력 크기 증가에 따라 어떤 상한 성장률 안에 들어가는지를 `O(f(n))` 형태로 표현해, 구현 환경 차이를 배제하고 알고리즘의 확장성을 비교하는 점근 표기법임.

기술사 답안에서는 빅오를 "실행시간"으로 단정하지 말고, **입력 변수**, **기본 연산**, **상한의 의미**, **최악·평균·상각 조건**을 함께 밝혀야 함.

```text
코드/알고리즘 -> 비용 함수 도출 -> 지배항 추출 -> O(f(n)) 표기 -> 후보 비교
                  T(n), S(n)        최고 성장항       상한        선택 판단
```

## 개념 정리

| 구분 | 의미 | 답안 포인트 |
|:---|:---|:---|
| `O(f(n))` | 비용이 `c·f(n)` 이하로 제한되는 상한 표기 | 최악 또는 보수적 증가율 설명 |
| `Theta(f(n))` | 상한과 하한이 모두 `f(n)`으로 맞는 정확한 차수 | tight bound가 필요할 때 사용 |
| `Omega(f(n))` | 최소한 이 정도는 든다는 하한 표기 | 문제 자체의 하한 설명 |
| 지배항 | 큰 입력에서 비용 증가를 사실상 결정하는 항 | 상수·하위항 제거 근거 |

예를 들어 `3n^2 + 10n + 7`은 큰 입력에서 `n^2` 항이 지배하므로 `O(n^2)`로 표현하지만, 작은 입력의 실제 실행시간이나 캐시 효과까지 설명하지는 못함.

## 분석 방법

1. **입력 크기 정의**: 배열 원소 수 `n`, 그래프 정점 `V`와 간선 `E`, 문자열 길이, 비트 수처럼 문제의 비용 단위를 정함
2. **기본 연산 선정**: 비교, 대입, 해시 계산, 간선 순회, 재귀 호출 등 비용을 대표하는 연산을 정함
3. **비용 함수 구성**: 반복문, 중첩 반복문, 재귀식, 자료구조 연산을 합산해 `T(n)` 또는 `S(n)`을 구함
4. **지배항 정리**: 상수 계수와 낮은 차수 항을 제거하고 성장률이 가장 큰 항을 남김
5. **조건 명시**: 최악, 평균, 최선, 상각, 기대 시간 중 어떤 성능 보장인지 함께 씀

빅오 분석은 수학 표기 자체보다 "무엇을 기준으로 비용을 세었는가"가 핵심이며, 입력 변수를 잘못 잡으면 맞는 표기처럼 보여도 설계 판단이 틀어짐.

## 대표 성장률 해석

| 표기 | 대표 구조 | 기술사적 해석 |
|:---|:---|:---|
| `O(1)` | 배열 인덱스 접근, 스택 push/pop | 입력 크기와 무관하지만 충돌·잠금·캐시 조건을 별도 확인해야 함 |
| `O(log n)` | 이진 탐색, 균형 트리 | 매 단계 후보가 일정 비율로 줄어드는 구조임 |
| `O(n)` | 선형 탐색, 전체 스캔 | 모든 원소 확인이 필요한 기본 비용임 |
| `O(n log n)` | 비교 기반 효율 정렬 | 대규모 정렬의 일반적 목표 수준임 |
| `O(n^2)` | 모든 쌍 비교, 단순 중첩 반복 | 입력 증가에 민감해 데이터 규모 제한이나 개선이 필요함 |
| `O(2^n)` 이상 | 완전탐색, 부분집합 탐색 | 정확성은 높아도 실무 규모에서는 가지치기·DP·근사 검토가 필요함 |

같은 빅오라도 상수 계수, 메모리 접근 패턴, 병렬화 가능성, 입출력 비용이 다르므로 최종 선택은 측정과 함께 결정해야 함.

## 실무 판단 기준

| 판단 질문 | 빅오만으로 부족한 이유 | 보완 기준 |
|:---|:---|:---|
| 운영 입력 크기에서 충분히 빠른가 | 작은 `n`에서는 상수 계수가 더 클 수 있음 | 기준 데이터 벤치마크, p95/p99 지연 |
| 최악 상황을 버틸 수 있는가 | 평균 `O(1)`이나 평균 `O(n log n)`은 입력 조건에 의존함 | 최악 입력 테스트, 상각 분석 |
| 병목 자원이 CPU인가 | 외부 정렬·분산 처리에서는 I/O와 네트워크가 지배적일 수 있음 | 블록 수, 네트워크 왕복, 메모리 피크 |
| 변수 하나로 충분한가 | 그래프·분산 시스템은 `n` 하나로 비용을 설명하기 어려움 | `V`, `E`, 파티션 수, 블록 수 분리 |

기술사 답안에서는 빅오 계층으로 후보를 1차 선별하고, 실제 시스템에서는 데이터 분포와 자원 병목을 측정해 최종 선택한다고 정리하는 것이 안전함.

## 오해와 감점 포인트

- **상한을 정확한 시간으로 오해**: `O(n^2)`는 실제 시간이 아니라 증가율 상한이며, 초 단위 예측값이 아님
- **평균과 최악 혼동**: 해시 테이블 평균 `O(1)`, 퀵 정렬 평균 `O(n log n)`은 조건부 성능임
- **상수항 제거 남용**: 작은 입력·실시간 시스템·임베디드 환경에서는 상수 비용이 품질을 좌우할 수 있음
- **공간복잡도 누락**: 시간만 `O(f(n))`으로 쓰고 보조 배열·재귀 스택·인덱스 공간을 빠뜨리면 설계 답안이 약해짐
- **로그 발생 이유 미설명**: `O(log n)`을 암기처럼 쓰지 말고 절반 축소, 균형 트리 높이처럼 구조적 원인을 설명해야 함

## 답안 작성 포인트

1. 정의는 "입력 크기 증가에 따른 비용의 상한 성장률 표기"로 시작함
2. `O`, `Theta`, `Omega`를 간단히 구분해 빅오가 상한임을 명확히 함
3. 반복문·재귀·자료구조 예시로 비용 함수가 어떻게 나오는지 1개 이상 설명함
4. 그래프 문제는 `O(V+E)`처럼 입력 변수를 분리해 단일 `n` 오해를 피함
5. 결론은 "빅오는 후보 선별 도구이고, 최종 판단은 입력 분포·최악 조건·자원 측정과 결합한다"로 마무리함

> 기술사 관점에서 빅오 표기법은 복잡한 알고리즘을 같은 척도에 올리는 언어이지만, 그 자체가 운영 성능 보증서는 아니므로 적용 조건을 함께 써야 함.
