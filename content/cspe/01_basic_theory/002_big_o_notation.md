# 빅오 표기법 (Big-O Notation)

## 1. 정의 및 개념

| 구분 | 정의 | 의미 |
|---|---|---|
| **Big-O, O(f(n))** | 입력 크기 `n` 증가 시 알고리즘 비용이 특정 함수의 상수배 이내로 제한됨을 나타내는 상한 표기 | 최악 또는 보수적 성장률 |
| **Big-Theta, Theta(f(n))** | 상한과 하한이 모두 같은 함수로 묶이는 정확한 차수 표기 | tight bound |
| **Big-Omega, Omega(f(n))** | 알고리즘 또는 문제 비용이 최소한 특정 함수 이상 필요함을 나타내는 하한 표기 | 최소 비용 또는 이론 하한 |

빅오 표기법은 실제 실행시간이 아니라 입력 규모가 커질 때 비용이 얼마나 빠르게 증가하는지를 비교하기 위한 점근 표기법이다.

## 2. 표기 도출 절차

1. **입력 크기 결정**
   - 배열 길이 `n`, 그래프의 `V/E`, 문자열 길이, 행렬 크기 등 분석 변수를 정한다.

2. **기본 연산 선택**
   - 비교, 대입, 해시 계산, 간선 순회, 재귀 호출 등 지배적 연산을 정한다.

3. **비용 함수 작성**
   - 반복 횟수, 재귀식, 자료구조 연산 비용을 합산해 `T(n)` 또는 `S(n)`을 만든다.

4. **지배항 추출**
   - `3n² + 10n + 7`은 큰 입력에서 `n²`가 지배하므로 `O(n²)`로 표현한다.

5. **조건 명시**
   - 최악, 평균, 최선, 상각, 기대 시간 중 어떤 조건의 표기인지 밝힌다.

## 3. 대표 성장률

| 표기 | 대표 알고리즘·자료구조 | 해석 |
|---|---|---|
| **O(1)** | 배열 인덱스 접근, 스택 push/pop | 입력 크기와 무관한 상수 시간 |
| **O(log n)** | 이진 탐색, 균형 트리 탐색 | 후보가 반복적으로 절반 또는 일정 비율로 축소 |
| **O(n)** | 선형 탐색, 단순 순회 | 모든 원소를 한 번 확인 |
| **O(n log n)** | 병합 정렬, 힙 정렬 | 효율적인 비교 기반 정렬 수준 |
| **O(n²)** | 모든 쌍 비교, 단순 이중 반복 | 입력 증가에 따른 급격한 비용 증가 |
| **O(2ⁿ), O(n!)** | 완전탐색, 순열 생성 | 조합 폭발, 대규모 실무 적용 곤란 |

## 4. 빅오와 실제 성능의 차이

| 빅오 표기의 장점 | 빅오만으로 부족한 점 |
|---|---|
| 하드웨어·언어 차이를 제거하고 알고리즘 구조 비교 가능 | 상수 계수와 캐시 지역성 반영 부족 |
| 대규모 입력에서 확장성 판단 가능 | 작은 입력에서는 실제 성능과 역전 가능 |
| 후보 알고리즘 1차 선별에 유리 | I/O, 네트워크, 동시성 병목 설명 부족 |
| 이론적 성능 보장 설명 가능 | 평균·최악·상각 조건을 별도 명시해야 함 |

빅오는 후보를 걸러내는 1차 기준이며, 최종 선택은 운영 데이터와 벤치마크로 확정해야 한다.

## 5. 심화 이슈 (기술사 포인트)

1. **상한 표기 오해**
   - `O(n²)`는 정확히 `n²`번 수행된다는 뜻이 아니라 상한 성장률이 `n²` 수준이라는 의미다.

2. **평균과 최악 혼동**
   - 해시 평균 `O(1)`과 최악 `O(n)`, 퀵 정렬 평균 `O(n log n)`과 최악 `O(n²)`를 구분해야 한다.

3. **다변수 복잡도**
   - 그래프 알고리즘은 `O(V+E)`처럼 정점과 간선을 분리해야 한다.

4. **상각 분석**
   - 동적 배열 확장처럼 일부 연산은 비싸지만 여러 연산에 분산하면 평균 비용이 낮아질 수 있다.

5. **운영 환경 보완**
   - 데이터 분포, 메모리 계층, 디스크 I/O, 네트워크 왕복, p95 지연을 함께 검증해야 한다.

## 6. 결론

빅오 표기법은 알고리즘 확장성을 같은 기준에서 비교하게 해 주는 핵심 도구이다. 그러나 기술사 답안에서는 표기 결과만 제시하지 말고, 입력 변수·기본 연산·분석 조건·운영 보완 지표를 함께 제시해야 실무적 판단으로 인정된다.
