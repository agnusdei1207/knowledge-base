# 📖 【암기용】 개념 완전 이해

> 목적: 빅오 표기법을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 함수 증가율의 상한을 단순화해 표현하는 표기법
- **왜 필요한가**: 실제 연산식에는 상수와 낮은 차수 항이 섞인다. 빅오는 n이 커질 때 지배하는 항만 남겨 알고리즘 간 규모 적합성을 비교하게 한다.
- **핵심 직관**: n이 커질수록 결과를 지배하는 최고차항만 보는 약속임

## 깊이 이해
- **배경·문제의식**: `3n^2+20n+5`와 `n^2`은 작은 n에서는 차이가 있지만, n이 충분히 커지면 n^2 항이 증가율을 지배한다. 빅오는 이런 장기 증가 패턴을 상한으로 묶는다.
- **작동 원리**: f(n) ≤ c·g(n)이 n0 이후 항상 성립하면 f(n)=O(g(n))이라 쓴다. 즉 g(n)은 f(n)의 점근적 상한 역할을 한다.
- **비유**: 도시 인구가 늘 때 교통량을 "대략 제곱으로 는다"라고 표현하는 것과 같다. 세부 신호등 수보다 증가 패턴을 보는 방식임.
- **구체 예시**: 이중 반복문 `for i in n, for j in n`은 n^2회 비교를 수행하므로 O(n^2). 병합정렬은 각 레벨 n개 처리 × log2 n레벨로 O(n log n).
- **흔한 오해·주의점**: Big-O는 최악 시간만 뜻하지 않는다. 평균 O(1) 해시 탐색, 최악 O(n)처럼 분석 조건을 함께 써야 함.

## 연결 개념
- Big-Theta — 상한과 하한이 같은 tight bound
- Big-Omega — 점근적 하한
- 복잡도 분석 — Big-O로 시간·공간 증가율 표현

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Big-O는 입력 n이 충분히 클 때 함수 f(n)의 증가율을 상수배 상한 g(n)으로 묶는 점근 표기법이다.
> 2. **가치**: 알고리즘의 구현 언어·CPU 차이를 제거하고 O(log n), O(n), O(n log n), O(n^2) 계층으로 선택 기준을 제공한다.
> 3. **판단 포인트**: Big-O만 쓰면 과대 상한이 될 수 있으므로 Θ, Ω, 평균·최악 조건을 함께 명시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 알고리즘 연산 횟수가 입력 n에 대해 증가하는 상한을 나타내는 표기법
- 배경: 대용량 입력에서는 상수 인자 최적화보다 증가율 차이가 처리 가능 여부를 좌우함
- 필요성: 복잡한 연산식을 단순 계층(O(log n), O(n), O(n log n), O(n^2))으로 요약해 설계 검토·코드 리뷰·성능 예측의 공통 기준으로 사용

## Ⅱ. 구조 및 구성요소

```text
실제식 f(n) -> 지배항 추출 -> 상수 제거 -> Big-O 상한
                  / Θ tight bound
                  / Ω lower bound
```

| 구성요소 | 역할 | 예시 |
|:---|:---|:---|
| f(n) | 실제 연산 횟수 함수 | 3n^2+20n+5 |
| g(n) | 상한 기준 함수 | n^2 |
| c, n0 | 상수배·기준 입력 | f(n)≤c·g(n), n≥n0 |
| Θ/Ω | tight bound·하한 보완 | Θ(n log n), Ω(n) |

> 요약: Big-O는 실제식을 상수배 상한 함수로 단순화하고, Θ·Ω가 경계 해석을 보완함.

## Ⅲ. 동작원리 및 흐름도

```text
코드/수식 입력 -> 반복 횟수 산정 -> 최고차항 선택
             -> 상수 제거 -> O(g(n)) 표기 -> 조건 명시
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 기본 연산 식별 | 비교·대입·해시 계산 |
| 2 | 반복·재귀 횟수 계산 | 단일 n, 중첩 n^2, 분할 log n |
| 3 | 지배항 선택 | n^2+n은 n^2 지배 |
| 4 | 상수 제거 | 4n log n은 O(n log n) |
| 5 | 분석 조건 표기 | 평균/최악/상환 구분 |

> 요약: Big-O 산정은 연산식 도출 후 지배항만 남기고 분석 조건을 명시하는 절차임.

## Ⅳ. 특징

| 구분 | Big-O | Big-Theta | 수치 판단 |
|:---|:---|:---|:---|
| 의미 | 점근적 상한 | 상한=하한 | O(n^2)는 O(n^3)도 가능 |
| 용도 | 최악 가능 범위 설명 | 정확한 증가율 설명 | Θ(n log n) 정렬 하한 |
| 장점 | 알고리즘 계층 비교 | 과대 표기 방지 | n=10^6에서 log2 n≈20 |
| 한계 | 상수·캐시·I/O 미반영 | 증명 부담 증가 | 10n vs 1000n 모두 O(n) |

> 요약: Big-O는 상한 비교에 적합하나, 정확한 증가율은 Θ와 입력 조건을 함께 제시해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | Big-O 표기 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 실제 연산식 전체 표기 | 하위 항·계수 제거, 최고차항만 잔존 | n이 충분히 큰 설계 검토 |
| 비용/성능 | 벤치마크 수치만 비교 | O(log n)~O(2^n) 계층 비교 | n=10^6 이상 처리 가능성 판단 |
| 운영/위험 | 상한만 제시 | Θ·Ω·평균/최악 조건 병기 | 과대 상한·조건 누락 방지 |

> 요약: Big-O는 상한 계층화 도구이며, Θ·Ω와 분석 조건을 함께 써야 선택 기준이 된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과대 표기 | O(n^3)처럼 느슨한 상한 사용 | tight bound Θ 병기 | 복잡도 리뷰 지적 건수 |
| 조건 누락 | 평균·최악·상환 미구분 | 표기 옆에 분석 조건 명시 | 문서 내 조건 표기율 |
| 실측 괴리 | 상수항·캐시·I/O 영향 | p95 지연·처리량·RSS 벤치마크 병행 | 예측 대비 측정 편차 |

> 요약: Big-O 리스크는 느슨한 상한, 조건 누락, 실측 괴리이며 보완 표기와 벤치마크로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표기 정확도 | O/Θ/Ω 의미 구분 | 코드 리뷰 체크리스트 |
| 입력 규모 | n 최대값과 허용 계층 매핑 | 설계서 검토 |
| 실측 검증 | p95·TPS·RSS 기록 | 부하 테스트, 프로파일러 |

> 요약: Big-O 적용 결과는 표기 정확도, 입력 규모, 실측 검증 3개 축으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 코드 리뷰: 중첩 루프·재귀·컬렉션 API의 O(1)/O(log n)/O(n) 비용을 주석 또는 설계서에 표기
2. 성능 기준: n=10^5 이상 배치 처리에서 O(n^2) 후보를 O(n log n) 정렬·인덱스 구조로 치환
3. 검증 기준: Big-O 예측 후 벤치마크로 p95 지연, 처리량 TPS, 메모리 RSS를 측정해 상수항 병목 확인

**결론 (2줄):**
- 기술사 판단: Big-O는 알고리즘 1차 선별 도구이며, 최종 선택은 입력 분포·메모리 예산·SLA 수치로 확정해야 함
- 향후 방향: 분산·GPU·캐시 친화 알고리즘에서는 연산 횟수와 데이터 이동량을 함께 표기하는 모델 필요
