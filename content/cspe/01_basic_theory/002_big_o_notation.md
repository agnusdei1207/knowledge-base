## 미리 알고가기

- 점근적 상한: 입력 $n$이 충분히 커진 뒤를 기준으로 비용이 어떤 함수의 상수배를 넘지 않는다고 못박는 한계이며, 도로의 최고 속도 제한처럼 "이 지점부터는 이 이상 늘어나지 않는다"는 선을 그음
- 정확한 차수: 상한과 하한이 같은 함수로 맞아떨어져 비용이 그 함수와 같은 속도로 커진다는 뜻이며 $\Theta$ 표기로 나타냄
- 하한: 비용이 특정 함수보다 더 작아질 수 없는 한계를 뜻하며 $\Omega$ 표기로 나타냄. 아무리 최적화해도 이 밑으로는 못 내려가는 바닥선과 같음
- 지배항: 입력이 커질수록 전체 비용 증가를 사실상 혼자 결정하는 최고차항임

## Ⅰ. 개요

- **정의/개념**: 빅오 표기법은 알고리즘 비용 함수에서 입력 크기 $n$이 커질 때 증가율을 지배하는 항만 남겨 상한을 $O(f(n))$로 표현하는 점근 표기법임
- **배경/필요성**: 구현 언어와 장비가 달라도 알고리즘 구조의 확장성은 비교해야 하므로, 대규모 입력에서 비용이 어디까지 늘어날지 공통 언어로 표현할 기준이 필요함

## Ⅱ. 특징

- 빅오는 절대 실행시간이 아니라 입력 증가에 따른 비용 상한을 보여주므로 구현 세부가 달라도 구조 비교에 쓸 수 있음
- 상수항과 하위항을 걷어내므로 설계 초기에 후보 알고리즘을 빠르게 걸러내는 데 유리함
- 보통 최악 경우 상한을 설명할 때 많이 쓰이므로 응답 상한과 용량 산정의 출발점이 됨
- 실제 체감 속도는 상수 비용, 캐시, 입력 분포에 영향을 받으므로 빅오만으로 성능을 단정할 수는 없음

## Ⅲ. 종류 및 비교

| 판단 기준 | $O$ | $\Theta$ | $\Omega$ |
|:---|:---|:---|:---|
| 뜻 | 비용이 이 함수보다 더 빠르게 커지지 않는 상한을 뜻함 | 비용이 이 함수와 같은 차수로 커진다는 뜻임 | 비용이 이 함수보다 더 작게 줄어들지 않는 하한을 뜻함 |
| 주로 쓰는 상황 | 최악 성능 보장과 용량 상한을 설명할 때 주로 씀 | 두 알고리즘이 실제로 같은 차수인지 비교할 때 주로 씀 | 더 줄이기 어려운 이론적 한계를 설명할 때 주로 씀 |
| 답하는 질문 | 이 알고리즘은 어디까지 느려질 수 있는가를 묻는 질문에 답함 | 이 알고리즘은 실제로 어느 차수로 커지는가를 묻는 질문에 답함 | 이 문제는 이보다 더 좋게 풀기 어려운가를 묻는 질문에 답함 |

> 요약: $O$는 상한, $\Theta$는 실제 차수, $\Omega$는 하한을 설명하므로 무엇을 보장하려는지 먼저 정하고 써야 함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비용함수 $T(n)$ | 알고리즘이 입력 $n$에서 실제로 수행하는 기본연산 횟수를 세어 만든 함수이며 이후 모든 표기법 판정의 원재료가 됨 |
| 상한 함수 후보 $f(n)$ | $T(n)$에서 지배항만 남겨 얻은 후보 함수로, $O(1), O(\log n), O(n), O(n \log n), O(n^2), O(2^n)$ 순의 성장률 계층 중 어디에 속하는지로 후보를 정함 |
| 임계값 $n_0$ | 입력이 이 값 이상으로 커진 뒤부터만 상한 관계가 성립하도록 잡는 시작점이며, 작은 $n$에서 벌어지는 예외적 역전을 판정에서 걸러냄 |
| 배수 상수 $c$ | $T(n) \le c \cdot f(n)$이 실제로 성립하도록 곱해주는 배수이며, 이런 $c$를 하나라도 찾을 수 있어야 $f(n)$이 진짜 상한으로 인정됨 |

> 요약: $T(n)$에서 뽑은 지배항 후보 $f(n)$이 $n_0$ 이후 구간에서 어떤 $c$로도 $T(n)$을 눌러줄 수 있어야 $O(f(n))$이 성립함

## Ⅴ. 원리 및 절차 흐름도

```text
+------------+      +--------------+      +--------------+      +--------------+
| 비용함수   | ---> | 상한 후보    | ---> | 하한 대조    | ---> | 차수 확정    |
| T(n) 도출  |      | O(f(n)) 검증 |      | Omega(f(n))  |      | Theta(f(n))  |
+------------+      +--------------+      +--------------+      +--------------+
```

1. **비용함수 도출**: 알고리즘의 각 단계를 기본연산 단위로 세어 $T(n)$을 구함
2. **상한 후보 검증**: 지배항으로 만든 $f(n)$ 후보에 대해 $n \ge n_0$인 모든 구간에서 $T(n) \le c \cdot f(n)$을 만족하는 $c$, $n_0$가 존재하는지 확인해 $O(f(n))$을 확정함
3. **하한 대조**: 같은 $f(n)$을 기준으로 $T(n)$이 그 아래로 더 줄어들 수 없는지 확인해 $\Omega(f(n))$ 성립 여부를 판단함
4. **차수 확정**: 상한과 하한이 같은 $f(n)$으로 맞아떨어지면 $\Theta(f(n))$으로 확정하고, 한쪽만 성립하면 $O$ 또는 $\Omega$ 단독 표기로 남김

## Ⅵ. 실무 적용 및 유의점

1. 설계 초기 알고리즘 후보를 좁히는 국면에서는 $O$ 표기로 상한부터 비교하되, 입력 규모가 작거나 상수 비용 차이가 큰 구간에서는 낮은 차수 후보가 오히려 더 느릴 수 있으므로 후보를 2~3개로 추린 뒤에는 실제 데이터 규모로 실행시간과 캐시 미스율을 측정해 최종안을 확정함
2. 대규모 정렬처럼 하한이 $\Omega(n \log n)$으로 이미 증명된 문제를 다루는 시스템에서는 비교 기반 정렬을 아무리 튜닝해도 그 벽을 넘지 못하므로, 이보다 빠른 처리량을 요구받으면 비교를 쓰지 않는 계수 정렬 방식으로 전환하고 키 분포 편차와 처리량으로 전환 적합성을 확인함

## Ⅶ. 결론

빅오 표기법은 설계 초기 후보를 $O$ 상한으로 좁히는 도구이지만, 하한이 $\Omega$로 증명된 문제에서는 그 벽을 인정하고 $\Theta$로 확정된 차수를 기준으로 접근 자체를 바꿀지 판단해야 함.
