## 미리 알고가기

- 점근적 상한: 입력 크기 $n$이 충분히 커질 때 복잡도가 어떤 함수의 상수배 이하임을 뜻함
- 지배항: 복잡도 증가율을 결정하는 최고차항임
- 최악 경우 분석: 입력 분포와 무관하게 보장해야 하는 상한 성능을 보는 방식임

## Ⅰ. 개요

- **정의/개념**: 빅오 표기법은 알고리즘 비용을 입력 크기 $n$의 함수로 나타낼 때 상수항과 하위항을 제거하고 증가율의 상한을 $O(f(n))$ 형태로 표현하는 점근 표기법임
- **배경/필요성**: 구현 언어와 하드웨어가 달라도 알고리즘 구조의 확장성은 비교해야 하므로, 대규모 입력에서 성능이 어떻게 악화되는지 공통 기준이 필요함

## Ⅱ. 특징

- 절대 실행시간이 아니라 입력 증가에 따른 비용 증가율을 표현하므로 구조적 비교에 적합함
- 보통 최악 경우 상한을 나타내므로 서비스 안정성 판단과 용량 산정에 유용함
- 상수와 하위항을 제거해 단순화하므로 설계 단계 의사결정에는 강하지만, 소규모 입력의 실제 체감 속도까지 대변하지는 못함
- 시간복잡도뿐 아니라 공간복잡도, 통신 비용, 메시지 수 증가율 같은 다른 자원 분석에도 같은 방식으로 적용 가능함

## Ⅲ. 종류 및 비교

| 판단 기준 | $O$ | $\Theta$ | $\Omega$ |
|:---|:---|:---|:---|
| 의미 | 상한 | 정확한 차수 | 하한 |
| 설계 활용 | 최악 성능 보장 판단 | 증가율 동급 비교 | 이론적 최소 한계 확인 |
| 대표 질문 | 이 구조가 어디까지 느려질 수 있는가 | 실제로 어느 차수로 커지는가 | 이보다 더 좋아질 수 있는가 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 비용 함수 $T(n)$ | 반복문, 재귀, 호출 수를 식으로 정리한 원식이며 먼저 정확한 식을 세워야 함 |
| 상수 계수 | 하드웨어, 구현 세부 차이에서 오는 배수항이며 빅오에서는 제거함 |
| 하위 차수 항 | 큰 입력에서 영향이 줄어드는 항이며 지배항 판별 후 제거함 |
| 지배항 | 증가율을 결정하는 최고차항이며 최종 빅오를 결정함 |

```text
+-------------+     +-------------+     +-----------+     +-----------+
| 비용 함수 T(n) | --> | 상수/하위항 제거 | --> | 지배항 선택  | --> | O(f(n)) |
+-------------+     +-------------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 식도출 | --> | 항분해 | --> | 지배항선정 | --> | O표기화 |
+----------+     +----------+     +----------+     +----------+
```

1. **식도출**: 반복문, 재귀식, 자료구조 연산을 바탕으로 $T(n)$을 세움
2. **항분해**: 상수항, 하위항, 최고차항을 구분함
3. **지배항선정**: 입력이 커질수록 가장 크게 증가하는 항을 선택함
4. **O표기화**: 지배항만 남겨 상한을 $O(f(n))$로 정리함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 빅오를 실측 시간으로 오해하면 $O(n)$이 항상 $O(n \log n)$보다 빠르다고 잘못 판단할 수 있음
   - 해결방안: 빅오는 구조 비교에 쓰고 실제 적용 여부는 벤치마크와 입력 크기별 실행시간으로 검증함
2. 문제: 그래프 문제를 $n$ 하나로만 표현하면 $V$와 $E$의 영향이 가려져 입력 규모 판단이 틀어짐
   - 해결방안: 문제 성격에 맞게 독립 변수를 다시 정의하고 변수 정의와 산출식 일치 여부로 검증함
3. 문제: 평균과 최악을 혼동해 평균 $O(1)$ 구조를 최악 보장처럼 설명하면 장애 대응이 틀어짐
   - 해결방안: 평균, 최악, 상각 분석 범위를 명시적으로 분리하고 문서와 설계서의 분석 기준으로 검증함

## Ⅶ. 적용 사례

- 검색 엔진 색인 설계에서는 선형 탐색 대신 로그 차수 탐색 구조를 선택하며, 검색 지연시간과 색인 갱신 비용으로 결과를 확인함
- 라우팅 알고리즘 비교에서는 그래프 크기 증가 시 후보 알고리즘의 증가율을 미리 비교하며, 정점 수 증가에 따른 계산시간으로 결과를 확인함
- 메모리 제한 장비에서는 시간뿐 아니라 공간 빅오를 함께 검토해 적용 가능 여부를 판단하며, 피크 메모리와 실패율로 결과를 확인함

## Ⅷ. 결론

빅오 표기법은 구현 세부가 아니라 입력 증가에 따른 비용 상한을 보는 기준이므로, 실제 설계에서는 입력 모델과 분석 범위를 먼저 정한 뒤 사용해야 함.
