# 빅오 표기법 (Big-O Notation)

## 1. 개요

- **정의/개념**: 빅오 표기법은 알고리즘 비용이 입력 크기 증가에 따라 특정 함수의 상수배 이내로 제한됨을 나타내는 점근적 상한 표기이다.
- **배경/필요성**: 하드웨어·언어·상수 계수 차이를 제거하고 알고리즘의 구조적 확장성을 비교하기 위해 필요하다.

빅오는 실제 실행시간이 아니라 큰 입력에서 비용이 증가하는 경향을 표현한다.

## 2. 특징 및 비교

| 표기 | 의미 | 사용 목적 |
|---|---|---|
| **O(f(n))** | 상한 성장률 | 최악 또는 보수적 비용 설명 |
| **Theta(f(n))** | 상한과 하한이 일치하는 정확한 차수 | tight bound 설명 |
| **Omega(f(n))** | 하한 성장률 | 문제 자체의 최소 비용 설명 |

| 복잡도 | 대표 예 | 해석 |
|---|---|---|
| `O(1)` | 배열 인덱스 접근 | 입력 크기와 무관 |
| `O(log n)` | 이진 탐색 | 후보 공간 반복 축소 |
| `O(n)` | 선형 탐색 | 전체 원소 확인 |
| `O(n log n)` | 효율적 비교 정렬 | 대규모 정렬의 일반 기준 |
| `O(n²)` | 모든 쌍 비교 | 입력 증가에 민감 |
| `O(2^n)` 이상 | 완전탐색 | 조합 폭발 |

빅오 비교는 성장률을 보는 관점이며, 실제 선택은 입력 규모, 상수 계수, 메모리 사용, 데이터 분포, 최악 조건까지 함께 판단해야 한다.

이 판단을 답안에서 설득하려면 표기 기호보다 입력 변수와 비용 함수가 먼저 분명해야 한다.

## 3. 구성요소/구조

1. **입력 변수 정의**: `n`, `V`, `E`, 문자열 길이, 비트 수 등 문제 규모를 정한다.
2. **기본 연산 선정**: 비교, 대입, 간선 순회, 해시 계산 등 비용 기준 연산을 정한다.
3. **비용 함수 작성**: 반복문, 재귀식, 자료구조 연산 비용을 합산한다.
4. **지배항 추출**: 상수 계수와 하위항을 제거한다.
5. **조건 명시**: 최악, 평균, 최선, 상각 중 어떤 조건인지 밝힌다.

```text
코드/알고리즘 -> 비용 함수 -> 지배항 -> O(f(n)) -> 후보 비교
```

도출 구조가 생략되면 빅오는 단순 암기 표기가 되므로, 뒤의 문제점도 상한 해석·입력 변수·운영 규모 오해를 중심으로 정리한다.

## 4. 문제점 및 개선방안

1. **상한 표기 과잉 일반화**
   - 빅오는 상한 중심 표기이므로 실제 평균 성능과 차이가 날 수 있다.
   - **개선방안**: 평균·최악 조건과 입력 분포별 벤치마크를 함께 제시한다.

2. **작은 입력에서의 역전**
   - 상수 계수를 제거하므로 작은 입력에서는 빅오가 낮은 알고리즘이 더 느릴 수 있다.
   - **개선방안**: 운영 입력 규모 기준으로 임계점을 측정한다.

3. **입력 변수 단순화**
   - 그래프 알고리즘을 `n` 하나로만 쓰면 간선 수 영향을 설명하지 못한다.
   - **개선방안**: `O(V+E)`, 블록 수, 네트워크 왕복 등 병목 변수를 분리한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 라이브러리 알고리즘 선택 | 정렬·탐색 후보를 빅오 계층으로 1차 선별 | 입력 크기별 실행시간 |
| DB 질의 최적화 | 조인·정렬·인덱스 비용을 행 수와 I/O 블록 수로 추정 | 실행 계획 비용, 읽은 블록 수 |
| 시스템 용량 산정 | 데이터 증가율에 따른 CPU·메모리 사용량을 추정 | 처리량, 메모리 피크 |

## 6. 결론

빅오 표기법은 알고리즘 확장성을 비교하는 공통 언어이다. 다만 선택 근거로 쓰려면 입력 변수, 기본 연산, 분석 조건, 메모리 영향, 운영 측정값까지 연결해 성장률이 실제 병목과 맞는지 확인해야 한다.
