## Ⅰ. 개요
- **정의**: 알고리즘의 T(N)(001 참조)을 입력 크기 N의 증가 차수로 표현하는 점근 상한 표기법
- **배경/필요성**: 상수 계수와 저차항을 제거하고 증가율만 비교해야 입력 규모가 커질 때의 알고리즘 성능을 간결하게 판단할 수 있음
- **비유**: 도시 간 이동 시간을 "몇 시간대"로 말하는 것과 같음 — 3시간 12분이든 3시간 45분이든 "약 3시간"으로 요약하여 비교를 쉽게 함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| O/Ω/Θ 세 표기법의 수학적 정의와 차이를 구분할 수 있는가 | 각 표기법이 상한/하한/동시 만족 중 어떤 경계인지 명시 | O만 서술하고 Ω·Θ를 누락하지 않을 것 |

> 요약: T(N)의 증가 차수만 남겨 알고리즘 간 확장성을 간결하게 비교하는 표기 체계임

## Ⅱ. 구성요소
```text
  점근 표기 체계
        |
  +-----+-----+-----+
  |           |           |
 O(g)       Omega(g)    Theta(g)
 상한        하한        동시 경계
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| $O(g(N))$ — 빅오 | $N \ge N_0$에서 $T(N) \le c \cdot g(N)$을 만족하는 양의 상수 $c$, $N_0$가 존재 — 점근 상한 | 배송비 상한이 5만원이면 실제로는 그 이하일 수 있음 |
| $\Omega(g(N))$ — 빅오메가 | $N \ge N_0$에서 $T(N) \ge c \cdot g(N)$을 만족하는 양의 상수 $c$, $N_0$가 존재 — 점근 하한 | 최소 배송비가 1만원이면 그보다 적게 들 수 없음 |
| $\Theta(g(N))$ — 빅세타 | $O(g(N))$이면서 $\Omega(g(N))$을 동시에 만족 — 점근적 tight bound | 배송비가 항상 2~3만원 구간 내에 있음 |
| 증가 차수 계층 | $O(1) < O(\log N) < O(N) < O(N \log N) < O(N^2) < O(2^N)$ 순서의 성장률 위계 | 걷기 < 자전거 < 자동차 < 비행기 순으로 속도 차이가 커지는 것 |

> 요약: O는 상한, Ω는 하한, Θ는 양쪽 경계이며 증가 차수 계층으로 알고리즘을 분류함

## Ⅲ. 절차
```text
T(N) 도출(001 참조) --> 최고차항 추출 --> 계수 제거 --> O/Omega/Theta 판정
```
- 1단계: **T(N) 도출** — 기본 연산 횟수를 N의 함수로 산출함(001 참조)
- 2단계: **최고차항 추출** — $T(N) = 3N^2 + 5N + 7$이면 $N^2$ 항만 남김
- 3단계: **계수 제거** — $3N^2$에서 상수 계수 3을 제거하여 $N^2$만 취함
- 4단계: **O/Ω/Θ 판정** — 상한만 보장하면 $O(N^2)$, 하한도 같으면 $\Theta(N^2)$으로 표기함

> 요약: T(N)에서 최고차항을 추출하고 계수를 제거한 뒤 경계 조건에 따라 표기법을 선택함

## Ⅳ. 문제점
- **상한 과대 표기**: O는 상한이므로 $O(N)$인 알고리즘을 $O(N^2)$로 써도 수학적으로 틀리지 않음 — 비교 정밀도가 떨어져 알고리즘 선택을 오도함
- **상수 계수 손실**: 동일 $O(N \log N)$이라도 상수 차이로 실측 성능이 수 배 차이남 — 작은 N에서 $O(N^2)$ 알고리즘이 $O(N \log N)$보다 빠를 수 있음
- **입력 분포 미반영**: 최악 기준 O 표기만으로는 실제 입력 분포에서의 기대 성능을 알 수 없음 — 평균 케이스가 중요한 응용에서 의사결정 오류가 발생함

> 요약: 상한 과대 표기, 상수 손실, 입력 분포 미반영이 점근 표기의 한계임

## Ⅴ. 개선방안
1. 단기: 가능한 한 Θ 표기를 사용하여 상한과 하한을 동시에 제시하고 과대 표기를 방지함
2. 중기: 점근 분석과 함께 대표 입력 크기별 실측 벤치마크를 병행하여 상수 계수의 영향을 확인함
3. 장기: 입력 분포를 반영한 평균 케이스 분석 또는 amortized 분석을 적용하여 실사용 패턴에서의 성능을 정밀하게 예측함

> 요약: Θ 활용, 실측 병행, 평균·amortized 분석으로 점근 표기의 한계를 보완함

## Ⅵ. 전망
- 발전 방향: 캐시 미스, 분기 예측 실패 등 하드웨어 특성을 반영한 세밀한 복잡도 모델(cache-oblivious 분석 등)로 확장됨
- 기술사적 판단: 알고리즘 설계 시 빅오 분석은 기본 소양이며, 실무에서는 프로파일링과 결합하여 병목 구간을 특정하는 것이 핵심임
- 기술사 제언: 점근 분석 결과와 실측 데이터를 함께 제시하여 이론적 타당성과 실무 적합성을 동시에 입증할 것
