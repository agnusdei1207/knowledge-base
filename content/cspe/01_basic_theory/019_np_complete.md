# 📖 【암기용】 개념 완전 이해

> 목적: NP-완전 문제를 처음 보는 사람도 완전 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: NP에 속하면서 모든 NP 문제를 다항시간 환원받는 가장 어려운 문제군
- **왜 필요한가**: 어떤 문제가 NP-완전임을 알면 정확해 알고리즘에 매달리기보다 근사·휴리스틱·제약 완화 전략을 선택할 수 있다.
- **핵심 직관**: 퍼즐의 답 검사는 다항시간인데, 답 탐색은 후보 수가 지수적으로 증가하는 문제들이다.

## 깊이 이해
- **배경·문제의식**: P는 다항시간에 풀 수 있는 문제, NP는 주어진 답을 다항시간에 검증할 수 있는 문제이다
- NP-완전은 NP 문제 중 난이도 기준점 역할을 한다
- **작동 원리**: 문제 A가 NP에 속하고, 알려진 NP-완전 문제 B를 A로 다항시간 환원할 수 있으면 A도 NP-완전이다
- 대표 기준 문제는 SAT이다
- **비유**: 여러 자물쇠 문제가 있는데, 가장 어려운 자물쇠 하나를 새 문제로 바꿔 풀 수 있다면 새 문제도 같은 난이도 등급으로 본다.
- **구체 예시**: 3-SAT, Vertex Cover, Hamiltonian Cycle, TSP Decision은 NP-완전 문제로 분류된다.
- **흔한 오해·주의점**: NP-완전은 "풀 수 없음"이 아니다
- 작은 입력은 완전탐색·DP·SAT Solver로 풀 수 있고, 큰 입력은 근사·휴리스틱이 필요하다

## 연결 개념
- P vs NP — 계산가능성과 검증가능성의 관계
- 다항시간 환원 — 난이도 비교 도구
- NP-Hard — NP 밖 최적화 문제까지 포함

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 추상 표현 대신 클래스·환원·알고리즘 선택 기준을 명시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NP-완전은 NP에 속하고 모든 NP 문제가 다항시간 환원되는 결정 문제군이다.
> 2. **가치**: 문제 난이도를 분류해 정확해·근사·휴리스틱·제약완화 중 구현 전략을 선택하게 함.
> 3. **판단 포인트**: NP 포함 증명, 알려진 NP-완전 문제로부터의 환원, 입력 규모별 대응 전략이 핵심임.

---

## Ⅰ. 개요 및 필요성

- 개요: NP-완전은 검증은 다항시간이나 해 탐색 후보가 지수적으로 증가하는 결정 문제 분류이다
- 배경: 실제 스케줄링·경로·배치 문제는 입력이 커질수록 정확해 탐색 비용이 급증한다
- 필요성: NP-완전 판단은 해결 불가능 선언이 아니라 알고리즘 전략 선택의 기준이다

---

## Ⅱ. 구조 및 구성요소

```text
P -> NP
NP-Complete -> NP and NP-Hard
NP-Hard -> at least as hard as every NP problem
Proof -> membership in NP + polynomial reduction
```

| 구성요소 | 역할 | 판단 기준 |
|:---|:---|:---|
| P | 다항시간 해결 가능 | `O(n^k)` 알고리즘 존재 |
| NP | 답 검증이 다항시간 | 인증서 검증 가능 |
| NP-Complete | NP 중 환원 기준 문제 | NP 포함+NP-Hard |
| NP-Hard | NP 문제 전체 이상 난도 | NP 소속 필요 없음 |

> 요약: NP-완전은 NP 내부의 결정 문제이며, NP 포함성과 NP-Hard 환원성을 동시에 만족한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
대상문제 A -> A in NP 증명 -> 기존 NP-C 문제 B 선택
          -> B <=p A 환원 -> A의 NP-Complete 판정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 대상 문제를 결정 문제로 정의 | Yes/No 형태 |
| 2 | 해 인증서 검증 절차 제시 | 다항시간 검증 |
| 3 | 알려진 NP-C 문제 선택 | SAT, 3-SAT, VC |
| 4 | 다항시간 환원 구성 | 해 보존, `O(n^k)` |

> 요약: NP-완전 증명은 NP 포함 확인 후 기존 NP-완전 문제를 다항시간에 변환하는 방식으로 수행한다.

---

## Ⅳ. 특징

| 구분 | P 문제 | NP-완전 문제 | 수치·기준 |
|:---|:---|:---|:---|
| 해결 가능성 | 다항시간 알고리즘 존재 | 다항시간 정확해 미확인 | P=NP 미해결 |
| 검증 | 다항시간 | 다항시간 | 인증서 크기 다항 |
| 대표 예 | 최단경로, MST | 3-SAT, TSP Decision | 결정 문제 중심 |
| 대응 | 정확 알고리즘 | 근사·휴리스틱·ILP·SAT | 입력 규모별 선택 |

> 요약: NP-완전 문제는 검증은 가능하나 일반 다항시간 정확해가 알려지지 않아 근사·제약 기반 접근이 필요하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | P 문제 | NP-완전 문제 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 다항시간 정확해 존재 | 다항시간 검증, 정확해 미확인 | 결정 문제와 인증서 정의 |
| 비용/성능 | 입력 증가 시 다항 증가 | 후보 탐색 지수 증가 가능 | 입력 규모와 SLA 분리 |
| 운영/위험 | 정확해 우선 | 근사·휴리스틱·Solver 운영 | 근사율·Gap·timeout 기록 |

> 요약: NP-완전 판단은 포기가 아니라 정확해와 근사·휴리스틱의 운영 조건을 나누는 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 정확해 집착 | 입력 규모 대비 지수 탐색 | cutoff, branch and bound, heuristic 전환 | timeout rate |
| 해 품질 불명 | 휴리스틱 결과 검증 부재 | lower bound, optimality gap 기록 | gap %, objective value |
| 모델링 오류 | 결정 문제 변환 누락 | Yes/No 정의, 인증서 검증 절차 명시 | validation failure count |

> 요약: NP-완전 실무 리스크는 시간 초과, 해 품질 불명, 모델링 오류이며 Gap과 timeout으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 분류 근거 | NP 포함과 환원 절차 제시 | 설계 리뷰 |
| 해 품질 | 근사율·Gap·objective 기록 | Solver log |
| 운영 | SLA 내 timeout 정책 동작 | 부하·시나리오 테스트 |

> 요약: 성공 기준은 난이도 분류 근거, 해 품질 지표, SLA 내 운영 정책이다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 스케줄링: 입력 30개 이하는 백트래킹+가지한정, 1,000개 이상은 휴리스틱·메타휴리스틱 적용
2. 경로 최적화: TSP는 Christofides 1.5-근사 또는 유전 알고리즘으로 시간 예산 내 해 산출
3. 검증 자동화: SAT/SMT Solver로 제약을 모델링하고 Time-out, Gap, 해 품질 기준을 기록함

**결론 (2줄):**
- 기술사 판단: NP-완전 판정 시 정확해 요구와 입력 규모를 분리하고, SLA 시간 안에서 근사율·Gap을 제시해야 함
- 향후 방향: 양자·AI 기반 탐색이 보조하더라도 P vs NP 미해결 조건에서 검증 가능한 휴리스틱 운영이 필요
