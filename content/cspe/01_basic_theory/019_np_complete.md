## 미리 알고가기

- 결정 문제: 답이 예 또는 아니오로 귀결되는 문제임
- 다항 시간: 입력 크기에 대한 계산 시간이 $O(n^k)$ 형태인 범주임
- 환원: 한 문제를 다른 문제 형태로 바꿔 난이도 관계를 보이는 방법임

## Ⅰ. 개요

- **정의/개념**: NP-완전 문제는 답을 다항 시간에 검증할 수 있고, 모든 $NP$ 문제가 다항 시간 안에 자신으로 환원될 수 있는 문제군임
- **배경/필요성**: 실무 최적화 문제 상당수는 효율적인 정확 해법을 갖지 않으므로, 문제를 NP-완전으로 분류하면 정확 해 탐색보다 근사, 휴리스틱, 제한 조건 완화로 전략을 바꿀 근거가 생김

## Ⅱ. 특징

- 해를 찾는 일과 해를 검증하는 일을 구분해 계산 난이도를 설명함
- NP-완전 판정은 특정 문제 하나의 난이도보다 문제군 전체와의 관계를 보여줌
- 하나의 NP-완전 문제가 다항 시간 해법을 가지면 모든 NP 문제에 큰 변화가 생김
- 실무에서는 이론 증명보다 해법 전략 전환 기준으로 더 자주 쓰임

## Ⅲ. 종류 및 비교

| 판단 기준 | $P$ | $NP$ | NP-완전 | NP-Hard |
|:---|:---|:---|:---|:---|
| 해 찾기 | 다항 시간 가능 | 미정 | 미정 | 미정 |
| 해 검증 | 다항 시간 가능 | 다항 시간 가능 | 다항 시간 가능 | 보장 없음 |
| 관계 | 쉬운 문제군 | 검증 가능한 문제군 | $NP$ 중 가장 어려운 핵심군 | $NP$보다 같거나 더 어려움 |
| 대표 예 | 정렬 | 부분집합 합 결정 | 3-SAT, 해밀턴 순환 결정 | TSP 최적화 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 문제 형식 | 답이 예/아니오로 나오는 결정 문제 형태임. 이 형태가 환원 논리를 세우기 쉬움 |
| 검증 절차 | 주어진 해가 맞는지 다항 시간 안에 확인하는 절차임. 이 절차가 있어야 $NP$ 문제로 볼 수 있음 |
| 환원 관계 | 이미 어려운 문제를 새 문제의 입력으로 바꾸는 관계임. 새 문제도 어렵다는 증명이 이 변환으로 성립함 |
| 해법 전략 | 정확 해, 근사, 휴리스틱 중 어떤 접근을 쓸지 정하며 실무 판단과 연결됨 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 문제 형식    | --> | 검증 절차    | --> | 환원 관계    | --> | 해법 전략    |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문제정의 | --> | NP확인 | --> | 환원구성 | --> | 난이도판정 |
+----------+     +----------+     +----------+     +----------+
```

1. **문제정의**: 문제를 결정 문제 형태로 정리함
2. **NP확인**: 주어진 해를 다항 시간 안에 검증할 수 있는지 확인함
3. **환원구성**: 이미 알려진 NP-완전 문제를 새 문제로 변환함
4. **난이도판정**: 두 조건이 모두 성립하면 NP-완전으로 분류함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 이론 분류를 실무 해법으로 오해해 NP-완전 판정만으로 실제 시스템 설계가 끝나지 않음
   - 해결방안: 입력 규모, 허용 오차, 시간 제한에 맞춰 근사 전략을 함께 설계하고 해 품질과 실행시간으로 검증함
2. 문제: 결정 문제와 최적화 문제를 혼동해 이론 증명은 결정 문제인데 실무는 최적화 문제인 경우가 많음
   - 해결방안: 증명용 문제 형식과 실무 목표 함수를 분리해 설명하고 문제 정의 일관성으로 검증함
3. 문제: 이론적으로 어렵다는 이유만으로 작은 입력에도 휴리스틱을 쓰면 정확 해법이 가능한 경우를 놓칠 수 있음
   - 해결방안: 입력 크기와 제한 시간을 기준으로 해법을 계층화하고 규모별 성능 측정으로 검증함

## Ⅶ. 적용 사례

- 물류 경로 계획에서는 TSP 계열 문제를 근사 알고리즘으로 풀어 비용을 절감하며, 총 이동거리와 계산시간으로 결과를 확인함
- 작업 배치 최적화에서는 스케줄링 문제에서 휴리스틱으로 해를 생성하며, 자원 활용률과 지연시간으로 결과를 확인함
- 암호 분석에서는 조합 폭발 특성을 이해해 완전 탐색 한계를 판단하며, 탐색 공간 크기와 성공 확률로 결과를 확인함

## Ⅷ. 결론

NP-완전 문제를 이해하는 목적은 난제를 과장하는 데 있지 않고 정확 해법을 고집할지 근사와 휴리스틱으로 전환할지 판단하는 데 있음.
