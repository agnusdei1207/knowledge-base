## 미리 알고가기

- 결정 문제: 답이 예/아니오로 표현되는 문제 형식임
- P: 결정론적 알고리즘으로 다항 시간에 풀 수 있는 결정 문제 집합임
- NP: 주어진 해 후보를 다항 시간에 검증할 수 있는 결정 문제 집합임
- 다항 시간 환원: 한 문제를 다른 문제로 다항 시간 안에 변환해 난이도를 비교하는 방법임
- NP-hard: 모든 NP 문제가 다항 시간 환원될 만큼 어려운 문제 집합이며 NP에 속할 필요는 없음

## Ⅰ. 개요

- **정의**: NP-완전 문제는 NP에 속하면서 동시에 모든 NP 문제가 다항 시간 환원될 수 있는, NP 내에서 가장 어려운 결정 문제 집합임. 어떤 문제가 NP-완전임을 보이면 알려진 다항 시간 정확 알고리즘을 기대하기 어렵다는 근거가 되므로, 근사 알고리즘, 휴리스틱, 특수 사례 제한, 지수 탐색 최적화 같은 해결 전략을 선택하기 위해 사용함.
- **배경/필요성**: NP-완전성은 “실무에서 절대 풀 수 없다”는 뜻이 아니라 일반 입력에 대한 다항 시간 정확 해법이 알려져 있지 않다는 복잡도 분류임. 입력 크기, 제약 조건, 허용 오차에 따라 실제 해결 전략은 달라질 수 있음.
- **비유**: 어떤 자물쇠가 가장 어려운 자물쇠 무리에 속한다는 것을 보이면, 모든 열쇠를 빠르게 찾는 만능 방법을 기대하기보다 우회 전략을 세우는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계산복잡도 분류와 해결 전략 이해 확인 | P, NP, NP-hard, 환원, 결정 문제 | NP-hard와 NP-complete 혼동 |

> 요약: NP-완전은 검증은 다항 시간에 가능하지만 모든 NP 문제만큼 어렵다는 환원 기반 난이도 분류임.

## Ⅱ. 특징/비교

| 판단 기준 | P | NP | NP-hard | NP-complete |
|:---|:---|:---|:---|:---|
| 의미 | 다항 시간에 해결 가능 | 해 후보를 다항 시간에 검증 가능 | NP의 모든 문제가 환원됨 | NP에 속하고 NP-hard임 |
| 문제 형식 | 결정 문제 | 결정 문제 | 결정/최적화 모두 가능 | 결정 문제 |
| 검증 가능성 | 해결 가능하므로 검증 가능 | 후보 검증 가능 | NP 밖일 수도 있음 | 후보 검증 가능 |
| 난이도 근거 | 효율적 알고리즘 존재 | 검증 기준 존재 | 모든 NP보다 어렵거나 같음 | NP 내 최고 난이도 |
| 선택 기준 | 정확 알고리즘 우선 | 분류와 검증 | 하한·난이도 주장 | 근사·휴리스틱 검토 |

> 요약: NP-완전은 NP와 NP-hard의 교집합이며, 환원 방향과 결정 문제 조건을 정확히 구분해야 함.

- SAT, 3-SAT, CLIQUE, Vertex Cover, Hamiltonian Cycle, TSP 결정 버전 등이 대표 사례임
- 최적화 문제는 보통 결정 문제 버전으로 바꿔 NP-완전성을 논의함
- 어떤 NP-완전 문제가 다항 시간에 풀리면 모든 NP 문제가 다항 시간에 풀려 `P=NP`가 됨

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 문제A    | ---> | 다항환원 | ---> | 문제B    |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| NP검증   |      | 난이도전달|     | NP완전성 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 결정 문제 | 예/아니오로 답하는 형태로 복잡도 분류의 기본 대상임 | 합격 여부 질문 |
| 해 후보 | 문제의 yes를 증명할 수 있는 증명서 또는 선택 집합임 | 제출 답안 |
| 검증 알고리즘 | 해 후보가 맞는지 다항 시간에 확인하는 절차임 | 채점 기준표 |
| 다항 시간 환원 | 기존 어려운 문제를 새 문제 인스턴스로 효율적으로 바꾸는 변환임 | 문제 번역기 |
| 완전성 증명 | NP 포함과 NP-hard 환원을 모두 보여 NP-완전임을 입증함 | 난이도 인증 |

> 요약: NP-완전성은 후보 검증 가능성과 기존 NP-완전 문제로부터의 다항 시간 환원을 함께 요구하는 구조임.

- 환원은 보통 알려진 NP-완전 문제에서 증명하려는 문제로 가야 난이도가 전달됨
- 변환은 yes 인스턴스를 yes로, no 인스턴스를 no로 보존해야 함
- NP-hard만 보이면 NP-완전이라고 말할 수 없으며, NP 포함성도 별도로 보여야 함

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 문제정식화| ---> | NP포함검증| ---> | 환원구성 | ---> | 전략선택 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 결정문제 |      | 후보검증 |      | yes/no보존|     | 근사/휴리스틱|
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 원문제가 결정 문제인지, 최적화 문제라면 결정 버전으로 바꿀 수 있는지 확인함
2. **NP 포함 확인** - 주어진 해 후보를 다항 시간에 검증할 수 있는 절차를 제시함
3. **NP-hard 환원 증명** - 알려진 NP-완전 문제를 대상 문제로 다항 시간 변환하고 yes/no 보존을 설명함
4. **해결 전략 도출** - NP-완전성이 확인되면 입력 제한, 근사, 휴리스틱, 분기한정, ILP/SAT Solver 등 대안을 선택함

> 요약: NP-완전 판단은 결정 문제 정식화, 후보 검증, 환원 증명, 현실적 해결 전략 선택으로 이어지는 흐름임.

- 환원 방향을 반대로 쓰면 쉬운 문제가 어려운 문제로 바뀔 수 있음을 보일 뿐 대상 문제의 어려움을 증명하지 못함
- 실무에서는 최악 복잡도와 평균 입력 난이도, 데이터 크기를 분리해 판단해야 함
- 근사 가능성은 문제마다 다르므로 NP-완전이라는 사실만으로 같은 대안을 적용할 수 없음

## Ⅴ. 문제점

- **P1 환원 방향 오류**: 증명하려는 문제에서 알려진 NP-완전 문제로 환원하면 대상 문제의 어려움을 보이지 못함
- **P2 실무 난이도 과대해석**: NP-완전이라는 분류만 보고 작은 입력, 특수 제약, 휴리스틱으로 풀 수 있는 경우까지 배제할 수 있음
- **P3 최적화 문제 혼동**: 최적값을 구하는 문제와 결정 문제 버전을 구분하지 않으면 NP, NP-hard, NP-complete 표기가 섞임

> 요약: NP-완전성의 문제는 개념 자체보다 환원 방향, 현실 적용, 문제 형식 구분을 잘못할 때 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 알려진 NP-완전 문제에서 대상 문제로 가는 환원 방향과 yes/no 보존 조건을 명시함 (확인: 환원 다이어그램)
- **P2 대응**: 입력 규모, 제약 조건, 허용 오차를 분석해 정확 알고리즘, 특수 사례 알고리즘, 근사, 휴리스틱을 구분 적용함 (확인: 데이터 규모별 실행 가능성)
- **P3 대응**: 최적화 문제는 결정 버전으로 정식화하고, 최적화 원문은 NP-hard로 표현하는지 검토함 (확인: 문제 형식 표기)

> 요약: NP-완전성 개선은 증명 형식을 엄격히 하고, 실무 해법은 입력 조건과 정확도 요구에 맞춰 선택하는 것임.

## Ⅶ. 전망

- **발전 방향**: SAT/SMT Solver, ILP, parameterized algorithm, approximation, 양자 알고리즘 연구는 NP-완전 문제 대응 전략을 계속 확장함
- **기술사적 판단**: NP-완전성은 포기 선언이 아니라 비용 한계를 설명하고 대안 전략을 정당화하는 근거로 사용해야 함
- **기술사 제언**: 답안에서는 `NP 포함 + NP-hard 환원 = NP-complete` 구조와 환원 방향을 반드시 도식화해야 함
