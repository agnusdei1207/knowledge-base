# 019. NP-완전 문제 (NP-Complete)

## 미리 알고가기

- **결정 문제 (Decision Problem)**: 질문의 답이 오직 "Yes" 또는 "No"로만 나오는 문제 유형임
- **다항 시간 (Polynomial Time)**: 입력 크기 $n$에 대해 수행 시간이 $O(n^k)$ 형태인 경우로, 컴퓨터가 현실적으로 해결 가능한 범주임
- **비결정론적 튜링 머신 (NTM)**: 동시에 여러 경로를 탐색할 수 있는 가상의 계산 모델로, NP의 정의에 사용됨

## Ⅰ. 개요

- **정의/개념**: NP-완전(NP-Complete)은 비결정론적 다항 시간(NP)에 속하는 문제들 중 가장 어려운 문제군으로, 모든 NP 문제를 다항 시간 내에 자신으로 환원(Reduction)할 수 있는 문제들의 집합임
- **배경/필요성**: 수많은 실무 문제(스케줄링, 최적 경로 등)들이 효율적인 해법($P$)을 찾지 못해 지수 시간의 복잡도를 가짐. NP-완전 분류를 통해 문제의 난이도를 객관적으로 파악하고, 무의미한 최적해 탐색 대신 근사해(Approximation)나 휴리스틱(Heuristic) 접근으로 전략을 수정하기 위해 사용함

## Ⅱ. 특징 및 비교

문제의 복잡도 계층은 '해를 찾는 비용'과 '해를 검증하는 비용'의 관계에 의해 정의됨.

| 분류 | 정의 및 특징 | 해 찾기 (Search) | 해 검증 (Verify) | 대표 예시 |
|:---|:---|:---|:---|:---|
| **P** | 다항 시간 내 해결 가능한 문제 | **다항 시간 ($O(n^k)$)** | 다항 시간 | 정렬, 최단 경로, MST |
| **NP** | 다항 시간 내 검증 가능한 문제 | 알 수 없음 (대개 지수) | **다항 시간** | SAT, TSP 결정 문제 |
| **NP-Hard** | 모든 NP 문제보다 어려운 문제 | 알 수 없음 | 알 수 없음 (NP 아닐 수 있음) | TSP 최적화 문제, 정지 문제 |
| **NP-Complete** | **NP이면서 동시에 NP-Hard인 문제** | 알 수 없음 | **다항 시간** | 3-SAT, Clique, 배낭 문제 |

> 요약: NP-완전 문제 중 단 하나라도 다항 시간 내에 풀 수 있음이 증명되면, $P=NP$가 성립하여 모든 NP 문제가 다항 시간 내에 풀리게 됨.

## Ⅲ. 구성요소/구조

어떤 문제 $L$이 NP-완전임을 증명하기 위해서는 소속성과 난해성을 동시에 입증해야 함.

- **증명 구성요소**:
  - **NP 소속성 (NP-Membership)**: 문제의 답(Certificate)이 주어졌을 때 다항 시간 내에 확인 가능함을 증명
  - **NP-난해성 (NP-Hardness)**: 이미 알려진 NP-완전 문제($L'$)를 문제 $L$로 다항 시간 내에 환원($L' \leq_p L$)할 수 있음을 증명
  - **다항 시간 환원 (Reduction)**: 문제 $A$의 입력을 문제 $B$의 입력으로 바꾸어, $B$의 답이 곧 $A$의 답이 되도록 변환하는 과정

- **문제 해결 전략 구조 (원리/흐름도)**:

```text
[Problem Classification] -> [Complexity Analysis] -> [Strategy Selection]
       |                         |                        |
  (New Problem)           (NP-Complete?)          (Exact/Approx/Heuristic)
```

1. **정확 알고리즘**: 입력 규모가 작은 경우($n < 20 \sim 30$)에만 지수 시간 알고리즘(Backtracking 등) 적용
2. **근사 알고리즘**: 최적해는 아니지만 최적해와 일정 비율 이내의 차이를 보장하는 다항 시간 해법 적용
3. **휴리스틱/메타휴리스틱**: 정답 보장은 없으나 실무적으로 우수한 해를 빠르게 도출 (유전 알고리즘, 담금질 기법 등)

## Ⅳ. 문제점 및 개선방안

1. **환원 방향의 오류 (Common Mistake)**: 새로운 문제 $B$의 난이도를 입증하기 위해 $B$를 이미 쉬운 문제인 $P$로 환원하는 우를 범함
   - **개선방안**: 반드시 "어렵다고 알려진 문제($A$) $\rightarrow$ 새로운 문제($B$)" 방향으로 환원을 수행하여, $A$의 난이도가 $B$에 포함됨을 보여야 함 (확인: 환원 로직의 방향성 검증)

2. **최적화와 결정 문제의 혼동**: NP-완전은 'Yes/No'를 묻는 결정 문제에 국한되나, 실무의 '최솟값 찾기' 같은 최적화 문제에 이를 혼용함
   - **개선방안**: 최적화 문제는 대개 NP-난해(NP-Hard)임을 명시하고, 이를 결정 문제(예: 비용 $K$ 이하 경로 존재?)로 변환하여 복잡도 논의를 진행함 (확인: 문제 정의의 형식성)

3. **입력 특성을 무시한 일반화**: 전체적으로는 NP-완전이라도 특정 조건(예: 간선 가중치가 모두 1이거나 트라이 구조인 경우)에서는 다항 시간에 풀릴 수 있음
   - **개선방안**: 문제의 특수한 제약 조건을 파악하여 해당 조건에서의 효율적 특수해(Special Case Algorithm)가 존재하는지 확인함 (확인: 입력 데이터의 도메인 특성)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 물류 배송 (TSP) | 수백 개의 배송 지점을 도는 경로(TSP)를 NP-난해로 판단하고, 탐욕법 또는 타부 서치(Tabu Search)로 경로 생성 | 총 주행 거리, 계산 시간 |
| 클라우드 스케줄링 | 수천 개의 작업을 서버에 배치(Bin Packing)할 때, 최적해 대신 근사 알고리즘(First Fit Decreasing) 적용 | 서버 자원 이용률, 대기 시간 |
| 암호학 (Knapsack) | 배낭 문제의 난해성을 이용한 공개키 암호 체계 구축 (현재는 분석되어 제한적 사용) | 암호 해독 난이도, 연산 속도 |
| 반도체 설계 (Partitioning) | 복잡한 회로 소자들을 칩 내부에 배치할 때 클리크(Clique)나 컷(Cut) 문제를 활용하여 최적 위치 추정 | 배선 길이, 칩 면적 효율 |

> 요약: 정확한 해를 구하기보다 현실적인 시간 내에 '충분히 좋은 해'를 찾는 전략 수립의 근거가 됨.

## Ⅵ. 결론

NP-완전 이론은 전산학에서 "무엇이 불가능한지"를 경계 짓는 가장 중요한 이정표임. 기술사는 어떤 문제가 NP-완전임을 파악하는 순간, 불필요한 최적해 탐색에 자원을 낭비하지 않고 비즈니스 요구사항에 맞는 근사 전략이나 휴리스틱 모델로 빠르게 전환할 수 있는 의사결정 능력을 갖추어야 함.

또한 최근에는 양자 컴퓨팅이나 근사 알고리즘의 발전으로 NP 문제에 대한 새로운 접근이 시도되고 있으나, 여전히 $P \neq NP$ 가정 하에서의 복잡도 분석은 시스템 설계의 기본임. 결국 NP-완전은 한계를 인정하고 그 안에서 최선의 실무적 대안을 찾아내는 기술적 지혜의 출발점임.
