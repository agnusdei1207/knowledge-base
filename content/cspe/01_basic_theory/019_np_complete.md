## Ⅰ. 개요

- **정의**: NP-완전은 NP에 속하면서 모든 NP 문제가 다항 시간에 환원되는 문제 부류임
- **배경/필요성**: 스케줄링·라우팅 같은 최적화 문제는 정확 알고리즘부터 설계하면 시간을 낭비할 수 있어, 착수 전에 "다항 시간 정확해가 원리적으로 존재하는가"를 먼저 판별해 근사·휴리스틱 대안으로 전환할 시점을 정해야 함
- **출제 의도**: P·NP·NP-hard·NP-complete의 포함관계와 다항 시간 환원을 통한 NP-완전성 증명 절차, 그리고 판별 후 실무 대안 선택 능력을 확인
- **답안 방향**: 네 집합의 관계 정의 -> 환원을 통한 NP-완전 증명 절차 -> 근사·휴리스틱 적용 판단 순으로 전개

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NP-완전 여부 판별과 대안 선택 근거 제시 | P⊆NP 포함관계, 다항 시간 환원(≤p)의 정의, 대표 NP-완전 문제 | NP-hard와 NP-complete 혼용, P=NP 미해결을 이미 증명된 사실로 단정, 검증과 풀이의 혼동 |

> 요약: 출제자는 NP-완전·NP-hard의 포함관계 구분과 환원 증명 절차 이해, 정확해 대신 근사·휴리스틱을 선택하는 판단력을 확인하려 함

## Ⅱ. 구조 및 구성요소

```text
NP-hard (모든 NP 문제가 다항시간 환원 가능한 문제 전체)
  |
  +-- NP (다항 시간 검증자가 존재하는 문제 전체)
  |     |
  |     +-- P (다항 시간에 직접 풀이 가능, P ⊆ NP)
  |     |
  |     +-- NP-complete = NP ∩ NP-hard (SAT, TSP, 배낭, 정점 커버 등)
  |
  +-- NP 밖의 NP-hard (예: 정지 문제 — 결정 불가능이라 검증자 자체가 없음)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 검증자(Verifier) | 후보 해가 주어졌을 때 다항 시간에 정답 여부를 판정 | 정답지로 채점하는 사람 |
| 다항 시간 환원(≤p) | 문제 A의 임의 인스턴스를 문제 B의 인스턴스로 $O(N^k)$에 변환 | 두 언어를 잇는 번역기 |
| NP-hard 문제 | 모든 NP 문제가 환원 가능한 문제(자신은 NP 밖일 수도 있음) | NP 경계 밖까지 걸친 난제 집합 |
| NP-complete 문제 | NP-hard이면서 동시에 NP에 속하는 교집합 | 검증은 가능하되 가장 어려운 문제 |

> 요약: NP-hard는 환원 가능성만 요구하는 넓은 집합이고, NP-complete는 그중 검증자까지 존재하는 교집합임

## Ⅲ. 동작원리 및 흐름도

```text
결정 문제 X 제시 -> 1.X∈NP 검증 -> 2.기존 NP-완전 Y 선택 -> 3.Y≤p X 환원 설계 -> 4.X NP-완전 확정
                                                                    |
                                                                    v
                                                    X가 이후 다른 문제 환원의 기준으로 재사용됨
```

- 1단계(NP 소속 검증): 후보 해가 주어지면 다항 시간에 참·거짓을 판정하는 검증자가 존재함을 보임
- 2단계(기준 문제 선정): 이미 NP-완전으로 확정된 문제 Y를 환원의 출발점으로 고름
- 3단계(환원 설계): Y의 임의 인스턴스를 X의 인스턴스로 $O(N^k)$에 변환하는 함수 f를 정의하고, Y 인스턴스가 참일 때만 f(Y)도 참임을 증명함
- 4단계(NP-완전 확정): X를 다항 시간에 풀면 Y도 풀리므로 X가 Y 이상으로 어렵다는 관계가 성립해 X의 NP-완전성이 확정됨

> 요약: 새 문제의 NP-완전성은 검증자 존재 확인과 기존 NP-완전 문제로부터의 다항 시간 환원, 두 단계로 증명됨

## Ⅳ. 특징

- NP-hard와 NP-complete 구분: NP-hard는 NP 소속 여부와 무관하게 모든 NP 문제가 환원되는 문제이며 정지 문제처럼 결정 불가능한 문제도 포함하지만, NP-complete는 그중 자신도 검증 가능한 부분집합만 가리킴
- 환원의 비대칭성: `Y ≤p X`는 "Y가 X보다 쉽거나 같다"는 의미이며, X를 다항 시간에 풀면 Y도 풀리지만 역은 성립하지 않음
- P=NP 가정 시 붕괴: P=NP가 성립하면 P·NP·NP-complete가 하나의 집합으로 합쳐지고, 이 가정에 안전성 근거를 둔 RSA 등 공개키 암호 체계의 전제가 무너짐
- 근사 알고리즘 존재 여부는 문제별로 다름: 정점 커버는 2-근사 알고리즘이 존재하지만, 삼각부등식이 성립하지 않는 일반 외판원 문제는 임의 근사비를 보장하는 다항 시간 알고리즘이 존재하지 않음(P≠NP 가정 시)

> 요약: NP-hard·NP-complete 구분과 환원의 방향성을 정확히 짚어야 하며, 근사 알고리즘 존재 여부는 문제 구조에 따라 갈림

## Ⅴ. 심화 비교 및 적용 판단

| 접근 | 정확해 보장 | 시간 복잡도 | 적용 조건 |
|:---|:---|:---|:---|
| 완전 탐색·동적계획법 | 보장 | 최악 지수, 의사다항시간(예: 배낭 $O(NW)$)은 가중치 상한이 클수록 사실상 지수적 | 입력 규모가 작거나 가중치 상한이 낮은 특수 구조 |
| 근사 알고리즘 | 근사비 이내 보장(예: 2-근사) | 다항 시간 | 근사비 증명이 존재하고 허용 가능한 최적화 문제 |
| 휴리스틱·메타휴리스틱 | 보장 없음 | 다항 시간(실무적) | 대규모 실무 문제, 근사비 증명보다 응답 시간이 우선 |
| SAT·제약만족 솔버(CDCL) | 완결 시 보장 | 최악 지수, 구조화된 인스턴스는 실무적으로 다항시간급 | 제약이 구조화된 문제(회로 검증, 스케줄링) |

> 요약: 정확해가 필수면 입력 규모를 제한한 완전 탐색·DP를, 근사비가 필요하면 근사 알고리즘을, 대규모 실무 최적화에는 휴리스틱·SAT 솔버를 선택함

**리스크·대응:**
- NP-완전 여부를 판별하지 않고 정확 알고리즘 개발을 요구 -> 기존 NP-완전 문제와의 환원 가능성을 사전 검토해 근사·휴리스틱 대안으로 전환(지표: 환원 가능성 검토 결과 문서화)
- 근사 알고리즘의 근사비를 검증 없이 실무 SLA에 그대로 적용 -> 근사비 증명값과 실측 성능을 분리해 보고(지표: 실측 해/참조 최적해 비율)

**도입 후 점검 지표:**
- 성능: 인스턴스 크기별 실행 시간 실측, 근사비 이내 여부 확인
- 품질: 근사해와 소규모 참조 최적해 간 편차율 추적

## Ⅵ. 실무 적용 및 결론

1. 단기: 신규 최적화·스케줄링 문제 설계 시 정점 커버·TSP·배낭 등 알려진 NP-완전 문제와의 환원 가능성부터 검토함
2. 중기: 근사비가 증명된 라이브러리(OR-Tools 등) 도입과 근사비·응답 시간 기준을 수립함
3. 장기: 문제 구조에 특화된 휴리스틱·SAT 솔버를 고도화하고, 파라미터화 복잡도(FPT) 기법으로 특수 사례를 다항 시간에 처리함

- 기술사적 판단: 신규 문제의 NP-완전성 판별이 정확해와 근사해 중 무엇을 추구할지 결정하는 최우선 기준임
- 기술사 제언: NP-완전 문제는 "풀 수 없는 문제"가 아니라 "정확해와 실행 시간을 동시에 보장할 수 없는 문제"이므로, 요구사항 단계에서 근사비와 응답 시간 중 우선순위를 명시해야 함
