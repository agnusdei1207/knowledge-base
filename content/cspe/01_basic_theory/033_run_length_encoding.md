## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 런랭스 인코딩(RLE, Run-Length Encoding)은 **연속으로 반복되는 동일 데이터(런, Run)**를 **값과 반복 횟수의 쌍**으로 압축하는 가장 단순한 무손실 압축 기법이다. "AAAAABBBCC" → "(A,5)(B,3)(C,2)"로 변환한다.
> 2. **가치**: 구현이 극히 단순(O(N) 시간·공간)하면서도 **반복이 많은 데이터**(흑백 이미지, 아이콘, 스프라이트, 초기 팩스)에서 압축률이 매우 높다. BMP, TIFF, PCX, PackBits 등 단순 이미지 포맷에 사용된다.
> 3. **융합**: 이미지(BMP RLE, JPEG의 0-런 압축), 팩시밀리(ITU-T T.4 MH 코딩), 게임(스프라이트 압축), 데이터베이스(컬럼 스토어 RLE 압축), 바이오(DNA 반복 서열) 등 반복 패턴이 있는 모든 데이터에 적용된다.

---

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| **런(Run)** | 동일한 값이 연속으로 반복되는 구간 | "같은 색 블록 줄" |
| **RLE(Run-Length Encoding)** | 런을 (값, 반복 횟수) 쌍으로 치환하는 무손실 압축 기법 | "같은 것 몇 개?" |
| **지그재그 스캔(Zigzag Scan)** | JPEG에서 8×8 DCT 블록을 대각선 순서로 읽어 0-런을 최대화하는 기법 | "대각선 줄 읽기" |

---

## Ⅰ. 개요 및 필요성

- **개념**: 입력 데이터를 스캔하면서 동일한 값이 연속으로 나타나는 구간(런)을 찾아, (값, 횟수)로 치환한다. 디코딩은 역으로 (값, 횟수)를 원래 연속 데이터로 복원한다.

- **필요성**: 흑백 팩스 문서에서 한 줄의 대부분은 흰색(0) 또는 검은색(1)의 긴 연속이다. 1,728픽셀 줄에서 "흰색 1,200개, 검색 300개, 흰색 228개" 같은 3개 쌍이면 충분하다. 원본 1,728비트 → RLE 수십 비트로 압축된다.

- **비유**: RLE는 **출석 부르기**와 같다. "김철수, 김철수, 김철수, 이영희, 이영희"를 "김철수 3명, 이영희 2명"으로 부르면 빠르다.

```text
+-----------------------------------------------------------------------+
|        RLE 인코딩/디코딩 예시                                         |
+-----------------------------------------------------------------------+
|                                                                       |
|  [원본] WWWWWWWWWBBBWWWWWWWWWBBB (24문자)                            |
|                                                                       |
|  [RLE 인코딩]                                                         |
|  W:9, B:3, W:9, B:3 → "9W3B9W3B" (8문자)                           |
|  압축률: 24→8, 67% 절감                                             |
|                                                                       |
|  [역효과 — 반복이 없는 데이터]                                       |
|  "ABCDEFG" → "1A1B1C1D1E1F1G" (14문자!)                            |
|  → 오히려 2배로 커짐!                                                |
|                                                                       |
|  ★ RLE는 반복이 많은 데이터에서만 효과적                             |
|  ★ 반복이 없으면 허프만/LZ77 등 다른 기법 필요                      |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** RLE의 장점과 한계를 보여준다. 반복이 많은 데이터(흑백 이미지)에서는 압축률이 극적이지만, 반복이 없는 텍스트에서는 오히려 크기가 증가한다. 이 때문에 RLE는 단독으로 쓰기보다 JPEG(양자화 후 0-런 RLE + 허프만)처럼 다른 기법과 조합하여 사용한다.

- **📢 섹션 요약 비유**: RLE는 "같은 색 블록을 개수로 세기"입니다. 빨간 블록이 100개 연속이면 "빨강×100"이 빠르지만, 색이 계속 바뀌면 효과 없습니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 시간 복잡도 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **런 탐지** | 연속 동일값 구간 식별 | O(N) | 선형 스캔 | 같은 색 세기 |
| **인코딩** | (값, 횟수) 쌍 출력 | O(N) | — | "빨강 5개" |
| **디코딩** | (값, 횟수) → 원본 복원 | O(N) | — | "빨강 5번 반복" |

### JPEG의 지그재그 RLE

- JPEG에서 8×8 DCT 블록을 양자화하면 대부분의 고주파 계수가 0이 된다. 지그재그(Zigzag) 순서로 스캔하면 0이 연속으로 나타나고, 이 0-런을 RLE로 압축한 후 허프만 코딩을 적용한다.

- **📢 섹션 요약 비유**: JPEG의 RLE는 "시험지에서 빈칸(0)이 연속인 부분을 '빈칸 15개'로 축약"하는 것입니다.

## Ⅲ. 비교 및 연결

### 비교 1: RLE vs 허프만 vs LZ77

| 비교 항목 | RLE | 허프만 | LZ77 |
|:---|:---|:---|:---|
| **압축 대상** | 연속 반복 | 빈도 불균등 | 반복 패턴 (비연속도 가능) |
| **구현 복잡도** | 매우 낮음 | 중간 | 높음 |
| **최적 데이터** | 흑백 이미지, 팩스 | 텍스트, 코드 | 범용 |
| **최악 성능** | 반복 없으면 크기 증가 | 균등 분포면 거의 무압축 | 패턴 없으면 미미 |

### 과목 융합 관점
- **데이터베이스**: Apache Parquet, Druid 등 컬럼 스토어는 정렬된 컬럼에서 같은 값이 연속되는 구간을 RLE로 압축한다.
- **게임**: 레트로 게임의 스프라이트(도트 이미지)는 배경색이 대부분이므로 RLE로 ROM 용량을 절약했다.

- **📢 섹션 요약 비유**: RLE는 "한 가지 잘하는 전문가"이고, LZ77은 "뭐든 적당히 잘하는 만능인"입니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — 팩시밀리 문서 압축**: ITU-T T.4(MH 코딩)는 흑백 팩스 문서의 각 줄을 RLE + 수정 허프만으로 압축한다. A4 한 페이지(약 3.7MB 원본)를 수십 KB로 압축하여 전화선으로 전송한다.

### 안티패턴
- **사진·자연 이미지에 RLE 단독 적용**: 자연 이미지는 픽셀값이 계속 변하므로 RLE가 오히려 크기를 증가시킨다. DCT/양자화 후 RLE(JPEG)처럼 전처리가 필수이다.

- **📢 섹션 요약 비유**: 자연 사진에 RLE를 쓰는 것은 "모든 사람의 이름이 다른 반에서 출석을 줄여 부르려는 것"과 같습니다. 줄일 게 없어요.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 비압축 | RLE 적용 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | 흑백 A4 팩스 3.7MB | RLE+허프만 수십 KB | **100배↑** 압축 |
| **정성** | 구현 복잡 | O(N) 단순 구현 | 임베디드에도 적용 가능 |

### 참고 표준
- **ITU-T T.4**: 팩시밀리 MH(Modified Huffman) 코딩 (RLE 기반)
- **BMP 파일 포맷**: RLE4/RLE8 압축 옵션

RLE는 가장 단순하지만, "반복"이라는 특성을 정확히 겨냥하는 전문화된 도구이다. 단독으로는 한계가 있지만, 전처리(DCT, 정렬) 후 다른 기법과 조합하면 강력한 압축 파이프라인의 핵심 단계가 된다.

### 👶 어린이를 위한 3줄 비유 설명

1. RLE는 "같은 것 몇 개?"로 줄이기예요. "●●●●●○○○" → "검정5, 흰색3"!
