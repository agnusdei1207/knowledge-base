## 미리 알고가기

- 런: 같은 값이 연속해서 나타나는 구간임
- 무손실 압축: 복호 결과가 원본과 완전히 같은 압축 방식임
- 반복 길이: 하나의 런에 포함된 동일 기호의 개수임
- 스캔 순서: 데이터를 읽는 방향이며 연속 반복 길이에 직접 영향을 줌
- 허프만 코딩: 기호 발생 빈도에 따라 가변 길이 접두 코드를 배정하는 무손실 압축 방식임
- 델타 코딩: 현재 값과 이전 값의 차이를 기록해 작은 변화량을 적은 비트로 표현하는 방식임

## 작성 근거(검토용)

- RLE 판단 기준은 빈도보다 연속성이므로 개요부터 결론까지 반복 길이에 일치시킴
- 비교표는 압축 메커니즘, 적합 입력, 주요 리스크로 RLE·허프만·델타 코딩을 구분함
- 구조 절은 구현에 필요한 최소 상태인 기호·카운터·토큰을 중심으로 정리함
- 절차 절은 입력을 한 번 순차 스캔하며 값과 반복 횟수를 만드는 동작을 보여주도록 작성함
- 압축 팽창과 스캔 순서는 RLE 적용 실패를 만드는 대표 원인임

## Ⅰ. 개요

- **정의/개념**: 런랭스 인코딩은 연속 반복 데이터를 값과 반복 횟수의 쌍으로 표현하는 무손실 압축 방식임
- **배경/필요성**: 반복 값이 많은 이미지·문서의 저장 크기를 줄이기 위해 반복 횟수 기반 부호화가 필요함

## Ⅱ. 특징

- 반복 구간이 길수록 값·길이 토큰으로 치환했을 때 압축 이득이 커짐
- 반복이 없으면 횟수 정보 때문에 오히려 데이터가 커짐
- 입력을 한 번 순차 스캔하며 현재 기호와 반복 횟수만 저장함

## Ⅲ. 종류 및 비교

| 판단 기준 | RLE | 허프만 코딩 | 델타 코딩 |
|:---|:---|:---|:---|
| 압축 메커니즘 | 연속 반복 구간을 값·횟수로 치환 | 빈도별 접두 코드 배정 | 이전 값과의 차이 기록 |
| 적합 입력 | 긴 동일값 반복 | 편중된 기호 빈도 | 작은 인접값 변화 |
| 주요 리스크 | 짧은 런에 따른 크기 증가 | 코드북에 따른 크기 증가 | 큰 차분값에 따른 크기 증가 |

> 요약: RLE는 동일 값의 연속 구간이 길어 값·길이 토큰이 원본보다 작을 때 적용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기호 | 반복 여부를 비교하는 데이터 값 |
| 카운터 | 현재 기호의 연속 길이 |
| 토큰 | 기호·반복 횟수의 압축 단위 |

```text
원본  : A A A A B B C D D D
런    : A4 B2 C1 D3
토큰  : (A,4) (B,2) (C,1) (D,3)
```

> 요약: RLE는 기호와 카운터로 연속 구간을 세어 값·길이 토큰을 생성함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+   +----------+   +----------+   +----------+
| 값 읽기  | -> | 반복 계산 | -> | 토큰 출력 | -> | 다음 값 이동 |
+----------+   +----------+   +----------+   +----------+
```

1. 첫 기호를 기준값으로 두고 카운터를 1로 초기화함
2. 다음 기호가 같으면 카운터를 증가시킴
3. 값이 바뀌면 기준값과 카운터를 토큰으로 출력함
4. 새 기호를 기준값으로 바꾸고 끝까지 반복함

> 요약: 한 번의 순차 스캔에서 값 변화 시점마다 이전 런을 토큰으로 확정함.

## Ⅵ. 실무 사례

1. 이미지 압축기는 반복 길이 임계값 이상에서만 RLE를 적용하고 압축 전후 크기를 비교함
2. 비트맵·문서 이미지 압축은 행·열 스캔별 압축률을 비교해 스캔 순서를 정함

## Ⅶ. 결론

- 런랭스 인코딩은 연속된 값을 값·반복 횟수 쌍으로 치환하므로 평균 런 길이와 토큰 크기를 기준으로 적용해야 함
