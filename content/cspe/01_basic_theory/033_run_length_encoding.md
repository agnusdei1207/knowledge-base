## 미리 알고가기

- **Run(런)**: 데이터 내에서 동일한 값이 연속해서 나타나는 덩어리 또는 구간
- **무손실 압축(Lossless Compression)**: 압축 후 복원했을 때 데이터의 손실이 전혀 없어 원본과 100% 일치하는 압축 방식
- **이스케이프 바이트(Escape Byte)**: 압축 데이터 내에서 '이 뒤의 값은 반복 횟수임'을 알리기 위해 사용하는 특수한 표식자

## 1. 개요

- **정의/개념**: 런랭스 인코딩(Run-Length Encoding, RLE)은 데이터 내에서 동일한 값이 연속적으로 나타날 때, 이를 개별적으로 나열하지 않고 '해당 값'과 '반복 횟수'의 쌍으로 치환하여 저장 공간을 줄이는 가장 단순한 형태의 무손실 압축 기법임
- **배경/필요성**: 팩스 문서의 흰 여백, 단색 배경이 많은 이미지, 메모리 덤프의 0으로 채워진 구간 등은 동일한 데이터가 수백, 수천 번 반복되는 특성을 가짐. 이를 하나하나 기록하는 것은 심각한 공간 낭비임. RLE는 이러한 '연속된 중복성'을 효율적으로 제거하여 파일 크기를 축소하며, 구현이 매우 단순하고 연산 오버헤드가 거의 없어 실시간 처리가 필요한 임베디드나 통신 환경에서 널리 사용됨

## 2. 특징 및 비교

### 가. 무손실 압축 기법 간의 특성 비교

| 구분 | 런랭스 인코딩 (RLE) | 허프만 코딩 (Huffman) | LZ 계열 (ZIP/PNG 등) |
|:---|:---|:---|:---|
| 압축 원리 | 연속된 동일 값의 횟수 기록 | 기호 출현 빈도 기반 가변 길이 할당 | 이전 문맥의 반복 패턴 참조 |
| 압축 이득 조건 | 긴 연속성(Run)이 많을 때 | 특정 기호가 편중되어 나올 때 | 단어/문구 단위 반복이 많을 때 |
| 압축 역전 현상 | 반복이 없으면 원본보다 커짐 | 모든 빈도가 고르면 발생 가능 | 드물게 발생 (오버헤드 탓) |
| 구현 난이도 | 매우 낮음 | 중간 | 높음 (사전/탐색 윈도우 필요) |
| 주요 용도 | 팩스, 단순 이미지, DB 컬럼 압축 | 텍스트, JPEG 최종 단계 | 범용 파일 압축, 통신 패킷 |

> 요약: 연속된 동일 값 제거에는 RLE, 확률적 중복 제거에는 허프만, 문맥적 중복 제거에는 LZ 방식이 적합함

### 나. RLE의 핵심 매커니즘
- **단순성**: 별도의 사전(Dictionary)이나 복잡한 통계 모델 없이 현재 값과 다음 값만 비교하면 됨
- **실시간성**: 스트리밍 데이터를 받으면서 동시에 압축과 복원이 가능하여 지연 시간이 극소화됨
- **조합 가능성**: 데이터의 분포를 한쪽으로 몰아주는 전처리(BWT, Zig-zag Scan 등)와 결합 시 시너지 발생

## 3. 구성요소/구조

### 가. RLE 데이터 변환 구조

```text
원본 데이터: A A A A A B B B B C C D A A (14 Bytes)

RLE 압축 예시 1 (순수 페어링):
[A, 5] [B, 4] [C, 2] [D, 1] [A, 2] (10 Bytes)

RLE 압축 예시 2 (이스케이프 방식):
A A A [ESC, 3] B B B [ESC, 2] C C D A A (12 Bytes, 3개 이상 시만 압축)
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 데이터 값 (Value) | 반복되는 원본 심벌 또는 픽셀 데이터 | 복원 시 출력할 실제 내용 |
| 런 길이 (Run Length) | 해당 데이터가 연속해서 나타나는 횟수 | 카운트 비트 수에 따라 최대 런 길이 제한 |
| 마커 (Marker/ESC) | 반복 구간의 시작을 알리는 특수 제어 코드 | 실제 데이터와 제어 코드를 구분하는 규칙 필수 |
| 블록 단위 | 압축을 수행하는 데이터의 덩어리 | 오류 파급을 막고 병렬 처리를 가능케 함 |

> 요약: 값과 횟수의 쌍을 기본 구조로 하되, 원본보다 커지는 것을 막기 위한 마킹 전략이 설계의 핵심임

## 4. 문제점 및 개선방안

1. **압축률 역전(Negative Compression)**: 'A B C D'와 같이 반복이 전혀 없는 데이터를 RLE로 처리하면 'A1 B1 C1 D1'이 되어 크기가 2배로 늘어남
   - **개선방안**: 반복 횟수가 특정 임계값(예: 3회) 이상일 때만 압축을 수행하거나, 압축하지 않은 원본 구간임을 표시하는 비트/플래그를 사용함

2. **비트 오류에 의한 도미노 현상**: 횟수(Length) 정보가 담긴 1바이트가 깨지면 이후의 모든 데이터를 읽는 위치가 어긋나 전체 파일이 파손됨
   - **개선방안**: 고정된 크기의 블록 단위로 독립 압축을 수행하고 블록 헤더에 무결성 체크섬(CRC)을 포함하여 오류 전파를 차단함

3. **카운터 오버플로우**: 반복 횟수가 카운터 변수의 최대값(예: 8비트의 경우 255)을 초과하는 경우
   - **개선방안**: 최대값 단위로 런을 분할하여 여러 개의 (값, 횟수) 쌍으로 기록하거나, 가변 길이 정수 인코딩을 통해 횟수를 표현함

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 팩스 전송 (G3/G4) | 흑백 픽셀의 연속 길이를 코드로 변환하여 전송량 획기적 절감 | 전송 시간, 페이지 당 데이터량 |
| 컬럼형 데이터베이스 | 동일한 값이 반복되는 열(Column) 데이터를 RLE로 저장하여 스토리지 최적화 | 디스크 I/O 절감, 질의 처리 속도 |
| 이미지 포맷 (BMP/TGA) | 단순한 그래픽이나 아이콘의 색상 반복 구간을 RLE 모드로 저장 | 파일 크기, 로딩 속도 |

> 요약: 데이터의 연속적인 중복이 보장되는 특수 목적의 저장 및 전송 분야에서 여전히 강력한 위상을 가짐

## 6. 결론

런랭스 인코딩은 복잡한 알고리즘 없이도 데이터의 구조적 중복을 효과적으로 제거할 수 있는 가장 경제적인 압축 기술임. 비록 범용적인 압축률은 낮을 수 있으나, 특정 도메인(이미지 마스크, 로그 파일 등)에서는 극강의 효율을 보여줌.

기술사는 데이터의 엔트로피를 분석하여 RLE가 적합한지 판단해야 하며, 특히 JPEG나 딥러닝 가중치 압축 등에서 볼 수 있듯이 데이터를 RLE가 잘 먹히는 형태(0이 많이 나오도록)로 먼저 가공한 뒤 RLE를 적용하는 계층적 압축 전략을 구사할 수 있어야 함.
