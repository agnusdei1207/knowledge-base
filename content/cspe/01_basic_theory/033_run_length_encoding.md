## 미리 알고가기

- 런(Run): 같은 값이 연속해서 나타나는 구간임
- 무손실 압축(Lossless Compression): 복호 결과가 원본과 완전히 같은 압축 방식임
- 반복 길이(Run Length): 하나의 런에 포함된 동일 기호의 개수임
- 스캔 방향(Scan Direction): 데이터를 읽는 방향이며 연속 반복 길이에 직접 영향을 줌
- 허프만 코딩(Huffman Coding): 기호 발생 빈도에 따라 가변 길이 접두 코드를 배정하는 무손실 압축 방식임
- 델타 코딩(Delta Coding): 현재 값과 이전 값의 차이를 기록해 작은 변화량을 적은 비트로 표현하는 방식임

## 작성 근거(검토용)

- **방향성**: 런랭스 인코딩은 반복 구간이 길수록 압축 이득이 커지는 대신 반복이 없으면 반복 길이 정보 때문에 오히려 데이터가 커지므로, 평균 런 길이를 측정해 임계값보다 짧으면 원본이나 다른 압축 방식으로 전환해야 함
- **개요 구성**: RLE 판단 기준은 빈도보다 연속성이므로 개요부터 결론까지 반복 길이에 일치시킴
- **Ⅱ. 특징 선정**: 반복 구간 길이에 따른 압축 이득·역전 위험·순차 스캔 방식을 선별해 RLE 고유의 동작 조건을 드러냄
- **Ⅲ. 비교축 선정**: 압축 메커니즘, 적합 입력, 주요 리스크로 RLE·허프만·델타 코딩을 구분하며 적합 입력 축이 언제 어느 방식을 쓰는지 가르는 적용 기준 역할을 함
- **Ⅳ·Ⅴ. 구조·절차 선정**: 구조 절은 구현에 필요한 최소 상태인 기호·카운터·토큰을 중심으로 정리하고, 절차 절은 입력을 한 번 순차 스캔하며 값과 반복 길이를 만드는 동작을 보여주도록 작성함
- **Ⅵ·Ⅶ. 사례·결론 선정**: 압축 팽창과 스캔 방향은 RLE 적용 실패를 만드는 대표 원인임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 런·반복 길이 정의와 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 런랭스 인코딩은 연속 반복 데이터를 값과 반복 길이의 쌍으로 표현하는 무손실 압축 방식임
- **배경/필요성**: 반복 값이 많은 이미지·문서의 저장 크기를 줄이기 위해 반복 길이 기반 부호화가 필요함

### 쉽게 이해하기 (학습용)
- 출석부에 같은 이름이 열 번 연달아 나오면 "이름 열 번"이라고 한 줄로 요약해 적는 것과 같음

## Ⅱ. 특징

- 반복 구간이 길수록 값·반복 길이 토큰으로 치환했을 때 압축 이득이 커짐
- 반복이 없으면 반복 길이 정보 때문에 오히려 데이터가 커짐
- 입력을 한 번 순차 스캔하며 현재 기호와 반복 길이만 저장함

### 쉽게 이해하기 (학습용)
- 줄 선 사람이 다 다른 옷을 입고 있으면 "무슨 옷 몇 명"이라 적는 게 오히려 더 길어지는 것과 같고, 처음부터 끝까지 한 번만 훑으며 방금 본 사람과 같은지만 확인함

## Ⅲ. 종류 및 비교

| 판단 기준 | RLE | 허프만 코딩 | 델타 코딩 |
|:---|:---|:---|:---|
| 압축 메커니즘 | 연속 반복 구간을 값·반복 길이로 치환 | 빈도별 접두 코드 배정 | 이전 값과의 차이 기록 |
| 적합 입력 | 긴 동일값 반복 | 편중된 기호 빈도 | 작은 인접값 변화 |
| 주요 리스크 | 짧은 런에 따른 크기 증가 | 코드북에 따른 크기 증가 | 큰 차분값에 따른 크기 증가 |

> 요약: RLE는 동일 값의 연속 구간이 길어 값·반복 길이 토큰이 원본보다 작을 때 적용함.

### 쉽게 이해하기 (학습용)
- 같은 물건이 쭉 이어질 때 개수만 적는 방법(RLE), 자주 나오는 물건에 짧은 이름을 붙이는 방법(허프만), 바로 앞 물건과의 차이만 적는 방법(델타 코딩)의 차이임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 기호 | 반복 여부를 비교하는 데이터 값 |
| 카운터 | 현재 기호의 반복 길이 |
| 토큰 | 기호·반복 길이의 압축 단위 |

```text
원본  : A A A A B B C D D D
런    : A4 B2 C1 D3
토큰  : (A,4) (B,2) (C,1) (D,3)
```

> 요약: RLE는 기호와 카운터로 연속 구간을 세어 값·반복 길이 토큰을 생성함.

### 쉽게 이해하기 (학습용)
- 지금 보고 있는 물건(기호)과 몇 개째인지 세는 손가락(카운터)으로 "같은 물건 몇 개"라는 메모(토큰)를 하나씩 만들어가는 것과 같음

## Ⅴ. 원리 및 절차 흐름도

```text
현재 값·반복 길이 설정 → 다음 값 비교
                         ├─ 같음 → 반복 길이 증가
                         └─ 다름 → 값·길이 토큰 출력 → 새 런 시작
```

1. 첫 기호를 기준값으로 두고 카운터를 1로 초기화함
2. 다음 기호가 같으면 카운터를 증가시킴
3. 값이 바뀌면 기준값과 카운터를 토큰으로 출력함
4. 새 기호를 기준값으로 바꾸고 끝까지 반복함

> 요약: 한 번의 순차 스캔에서 값 변화 시점마다 이전 런을 토큰으로 확정함.

### 쉽게 이해하기 (학습용)
- 물건을 하나씩 보면서 앞의 것과 같으면 손가락을 하나 더 접고, 다른 물건이 나오면 지금까지 센 개수를 메모하고 다시 처음부터 세는 과정임

## Ⅵ. 실무 사례

1. 이미지 압축기는 같은 값이 일정 길이 이상 반복되는 구간에만 RLE를 적용함
2. 비트맵·문서 이미지는 반복 구간이 더 길게 나타나는 스캔 방향으로 RLE를 수행함

### 쉽게 이해하기 (학습용)
- 벽지 무늬가 충분히 길게 이어질 때만 "같은 무늬 반복"이라 적고, 가로·세로 중 무늬가 더 길게 이어지는 방향을 골라 적는 것과 같음

## Ⅶ. 결론

- 런랭스 인코딩은 연속된 같은 값을 값·횟수로 줄이며, 반복 구간이 짧으면 오히려 데이터가 커질 수 있음
- 입력 블록의 평균 런 길이를 먼저 측정하고 임계값보다 짧으면 원본·다른 압축 방식으로 자동 전환해야 함

### 쉽게 이해하기 (학습용)
- 반복이 충분히 길 때만 요약이 이득이므로, 먼저 얼마나 반복되는지 재보고 반복이 적으면 요약을 포기하고 원본이나 다른 방법을 쓰는 것과 같음
