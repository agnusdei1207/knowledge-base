## Ⅰ. 개요
- **정의**: 연속 동일 데이터를 (값, 반복 횟수) 쌍으로 치환하는 무손실 압축 기법
- **배경/필요성**: 데이터에 동일 값이 연속되는 구간이 많을 때 저장·전송 비용을 줄이는 가장 단순한 접근이 필요함
- **비유**: "흰 칸 50개" 대신 "흰×50"으로 메모하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 압축 원리의 기초 이해 | (값, 횟수) 쌍 변환 구조 | 압축률이 데이터 특성에 의존한다는 점 명시 |
| 소스 코딩 기법 비교(034 참조) | 허프만(032 참조)과의 차이 | 텍스트처럼 연속 반복이 적은 데이터에선 오히려 팽창 가능 |

> 요약: 연속 동일 값을 (값, 횟수)로 압축하는 단순 무손실 기법임

## Ⅱ. 구성요소
```text
입력 스트림 --> Run 검출기 --> (값, 횟수) 쌍 생성기 --> 출력 스트림
                  |                    |
                  v                    v
            현재 값 비교           카운터 관리
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Run | 동일 값이 연속되는 구간 단위 | 같은 색 타일이 이어진 한 줄 |
| 값(Symbol) | Run을 구성하는 데이터 값 | 타일의 색상 |
| 횟수(Count) | Run 내 반복 길이 | 같은 색 타일의 개수 |
| 카운터 비트폭 | 횟수를 표현하는 고정/가변 비트 수 | 메모장 칸 크기 |

> 요약: Run 단위로 값과 횟수를 쌍으로 묶어 출력하는 구조임

## Ⅲ. 절차
```text
입력 읽기 --> 현재 값과 이전 값 비교 --> 같으면 카운터 증가
                                    --> 다르면 (값, 카운터) 출력 후 초기화
                                    --> 입력 종료 시 마지막 쌍 출력
```
- 1단계: 입력 스트림에서 첫 심볼을 읽고 카운터를 1로 초기화함
- 2단계: 다음 심볼을 읽어 이전 심볼과 비교함
- 3단계: 동일하면 카운터를 증가시키고, 상이하면 (값, 카운터) 쌍을 출력 후 새 심볼로 초기화함
- 4단계: 입력이 끝나면 마지막 (값, 카운터) 쌍을 출력하고 종료함

> 요약: 심볼 비교-카운터 증가-쌍 출력의 순환으로 동작함

## Ⅳ. 문제점
- 데이터 의존성: 연속 반복이 적은 데이터(자연어 텍스트 등)에서 카운터 오버헤드로 원본보다 크기가 증가함
- 카운터 오버플로: 고정 비트폭 카운터 사용 시 Run 길이가 최대값을 초과하면 하나의 Run을 분할해야 하여 효율이 저하됨
- 단독 사용 한계: 엔트로피 하한(032 참조)에 접근하지 못하여 범용 압축률이 낮음

> 요약: 데이터 특성 의존, 카운터 제한, 낮은 범용 압축률이 주요 한계임

## Ⅴ. 개선방안
1. 단기: 적용 전 데이터 Run 분포를 분석하여 압축 효과가 있는 채널에만 선택 적용함
2. 중기: 가변 길이 카운터(Escape 코드 방식)를 도입하여 오버플로 없이 긴 Run을 처리함
3. 장기: 허프만(032 참조)·LZW 등 엔트로피 코딩과 결합하여 2단계 압축 파이프라인을 구성함

> 요약: 선택 적용, 가변 카운터, 엔트로피 코딩 결합 순으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: TIFF·BMP·팩스(ITU-T T.4) 등 흑백 이미지 영역에서 표준 압축 단계로 지속 활용됨
- 기술사적 판단: 단독보다 전처리 단계로서의 가치가 높으며, 복합 코덱 내 1차 필터로 역할이 고정됨
- 기술사 제언: 압축 기법 선택 시 데이터 Run 특성 분석을 선행하고, 후단 엔트로피 코딩과의 조합 설계를 권고함
