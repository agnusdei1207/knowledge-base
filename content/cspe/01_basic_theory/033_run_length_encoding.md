## 미리 알고가기

- Run: 같은 값이 연속으로 반복되는 구간임
- RLE: 반복 구간을 값과 반복 횟수의 쌍으로 표현하는 무손실 압축 방식임
- 리터럴: 반복 압축하지 않고 원본 값을 그대로 기록하는 구간임
- 카운터 폭: 반복 횟수를 표현할 수 있는 최대 길이를 결정하는 비트 수임
- 압축비: 원본 크기 대비 압축 후 크기이며 데이터 특성에 따라 1보다 커질 수도 작아질 수도 있음

## Ⅰ. 개요

- **정의**: 런랭스 인코딩은 같은 심볼이 연속되는 구간을 `(값, 반복 횟수)`로 치환해 반복 데이터의 저장 크기를 줄이는 무손실 압축 기법임
- **배경/필요성**: 일부 데이터는 같은 색, 같은 공백, 같은 0 값이 길게 이어지므로 복잡한 통계 모델 없이 순차 스캔만으로 저장 공간과 전송량을 줄일 수 있는 단순한 압축 방식이 필요함.
- **비유**: `AAAAABBBCC`를 글자 하나하나 쓰지 않고 `A5 B3 C2`처럼 개수로 적는 방식과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| RLE 압축 원리 설명 | 반복 구간, 값-횟수 쌍, 무손실 복원 | 모든 데이터에서 압축된다고 오해 |
| 다른 압축과 선택 기준 비교 | 공간적 반복, 허프만의 통계적 중복과 차이 | 허프만·LZ와 원리 혼동 |

> 요약: RLE는 연속 반복이라는 구조적 중복이 클수록 효과가 커지는 단순 무손실 압축 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | RLE | 허프만 코딩 |
|:---|:---|:---|
| 제거 대상 | 같은 심볼의 연속 반복을 줄임 | 심볼 출현 확률의 차이를 줄임 |
| 데이터 조건 | 긴 run이 많을수록 유리함 | 빈도 분포가 치우칠수록 유리함 |
| 구현 방식 | 순차 스캔과 카운터만으로 구현 가능함 | 빈도표와 트리 또는 코드북이 필요함 |
| 선택 기준 | 흑백 이미지, 마스크, 단순 패턴에 적합함 | 텍스트, 범용 압축의 통계 부호화에 적합함 |

> 요약: RLE는 반복 구간 중심 압축이므로 데이터의 공간적 중복이 선택 기준이며, 통계 부호화와 결합해 보완할 수 있음.

- **압축 기준**: 반복 구간의 평균 길이가 값+카운터 오버헤드보다 충분히 클 때 이득이 발생함.
- **운영 기준**: 비반복 구간을 어떻게 표현하는지에 따라 작은 데이터의 팽창 여부가 달라짐.
- **결합 기준**: RLE는 단독보다 필터링, 델타 변환, 허프만 코딩 앞단에서 전처리로 쓰일 때 효과가 커짐.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Input      | ---> | Run        | ---> | Pair       |
| Stream     |      | Detector   |      | Encoder    |
+------------+      +------------+      +------------+
       |                   |                   |
       v                   v                   v
+------------+      +------------+      +------------+
| Literal    |      | Counter    |      | Output     |
| Segment    |      | Width      |      | Stream     |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 스트림 | 압축할 심볼의 순서열이며 동일 값의 연속성을 검사하는 대상임 | 타일이 늘어선 줄 |
| Run 탐지기 | 현재 심볼과 다음 심볼을 비교해 반복 구간의 시작과 끝을 찾음 | 같은 색 구간 찾기 |
| 카운터 | 반복 횟수를 저장하며 비트 폭에 따라 한 번에 표현 가능한 길이가 정해짐 | 개수 세는 계수기 |
| 값-횟수 쌍 | 반복 심볼의 값과 길이를 출력하는 압축 단위임 | 이름표와 수량표 |
| 리터럴 처리 | 반복이 짧은 구간은 원본 그대로 쓰거나 별도 플래그로 표시함 | 낱개 포장 |

> 요약: RLE는 입력을 순차적으로 읽어 반복 구간을 찾고, 값과 카운터를 출력하되 비반복 구간은 리터럴로 관리하는 구조임.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Read       | ---> | Count      | ---> | Emit       | ---> | Continue   |
| Symbol     |      | Run Length |      | Pair       |      | or Finish  |
+------------+      +------------+      +------------+      +------------+
```

1. **심볼 읽기**: 입력 스트림의 현재 심볼을 읽고 run의 시작점으로 지정함.
2. **반복 길이 계산**: 다음 심볼이 같은 동안 카운터를 증가시키고 카운터 최대값을 넘으면 구간을 분할함.
3. **출력 기록**: 반복 길이가 임계값 이상이면 `(값, 횟수)`를 기록하고, 짧으면 리터럴로 기록함.
4. **복원 검증**: 압축 스트림을 다시 펼쳐 원본과 동일한지 확인하고 압축비를 계산함.

> 요약: RLE는 현재 값의 연속 길이를 세고 반복이면 쌍으로, 아니면 리터럴로 기록한 뒤 무손실 복원을 확인함.

## Ⅴ. 문제점

- **P1 데이터 팽창**: 반복이 짧거나 거의 없는 데이터에서는 값과 카운터를 저장하는 오버헤드 때문에 원본보다 커질 수 있음.
- **P2 카운터 한계**: 고정 폭 카운터는 매우 긴 run을 한 번에 표현하지 못해 분할과 추가 플래그가 필요함.
- **P3 잡음 민감성**: 한두 개의 다른 값이 반복 구간 사이에 끼면 run이 잘려 압축 효과가 크게 떨어짐.

> 요약: RLE의 한계는 반복 부족, 카운터 표현 범위, 잡음에 의한 반복 구간 분절에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: PackBits처럼 반복 구간과 리터럴 구간을 플래그로 구분하고, 이득이 없으면 비압축 블록을 선택함. (확인: 압축 후 크기)
- **P2 대응**: 가변 길이 카운터나 연속 분할 인코딩 규칙을 정의해 긴 run을 안전하게 표현함. (확인: 최대 run 길이 테스트)
- **P3 대응**: 델타 변환, 예측 필터, threshold 기반 전처리로 반복 구조를 강화한 뒤 RLE를 적용함. (확인: run 평균 길이)

> 요약: RLE는 리터럴 모드, 가변 카운터, 전처리를 결합해 팽창과 긴 run, 잡음 문제를 완화해야 함.

## Ⅶ. 전망

- **발전 방향**: BMP, TIFF, PCX 같은 레거시 포맷뿐 아니라 마스크 이미지, sparse tensor, bitmap index에서 RLE 계열 표현은 계속 활용될 전망임.
- **기술사적 판단**: RLE는 범용 압축기보다 데이터 특성이 명확한 반복 스트림에 적용할 때 비용 대비 효과가 큼.
- **기술사 제언**: 답안에서는 반복 구간 기반 압축이라는 핵심과 함께 허프만·LZ 계열과의 선택 기준을 분명히 제시해야 함.
