## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 연속해서 반복되는 동일한 데이터(Run)를 데이터 값과 반복 횟수(Length)의 쌍으로 묶어 표현하는 가장 단순한 무손실 압축 기법임 |
| 배경/필요성 | 단순한 패턴이 길게 반복되는 파일(아이콘, 팩스 이미지 등)의 크기를 연산 오버헤드 없이 빠르게 줄이기 위해 필요함 |
| 출제 의도 | 압축 알고리즘의 기초 개념 파악 및 데이터 특성에 따른 압축 효율성(장단점) 판별 능력 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|   Raw Data        | ----> |     Run           | ----> | Length (Count)    |
| (e.g. AAAAABBB)   |       | (Repeated Symbol) |       | (Number of times) |
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 원본 데이터 | 압축되지 않은 일련의 기호 또는 픽셀 스트림 | 흩어진 색연필들 |
| 런 (Run) | 연속적으로 반복 출현하는 특정 기호 자체 | 색연필의 '색상' |
| 랭스 (Length) | 해당 기호가 연속해서 나타난 횟수 | 같은 색의 '개수' |
> 요약: RLE는 AAAAA를 (A, 5)로 치환하여 데이터와 연속 횟수라는 두 가지 요소로 정보를 요약함

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 데이터 스캔 | -> | 2. 반복 계수기 | -> | 3. 쌍(Pair) 생성| -> | 4. 결과 출력   |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 데이터 스캔: 스트림의 첫 번째 문자부터 순서대로 읽기 시작함
2. 반복 계수기: 이전 문자와 현재 문자를 비교하며 같으면 카운트를 증가시키고, 다르면 계수를 중지함
3. 쌍(Pair) 생성: 연속이 끊기는 시점에서 (문자, 반복 횟수)의 쌍을 생성하여 압축 버퍼에 기록함
4. 결과 출력: 스트림 끝까지 이 과정을 반복하고 완성된 요약 형태를 출력 파일로 저장함
> 요약: 데이터를 순차적으로 스캔하며 연속성을 확인하고, 끊길 때마다 (값, 횟수) 쌍으로 변환함

## Ⅳ. 문제점
- 역효과 발생(Negative Compression): ABCD처럼 데이터가 반복되지 않고 매번 바뀔 경우, 횟수 정보(1)가 추가되어 오히려 파일 크기가 2배로 커짐
- 한정된 적용 분야: 복잡한 텍스처를 가진 사진이나, 변화가 잦은 자연어 텍스트 파일에서는 압축 효율이 극히 낮음

## Ⅴ. 개선방안
- 하이브리드 압축 적용: 반복 데이터는 RLE로 처리하고 비반복 데이터는 플래그(Flag) 비트로 구분해 원본 그대로 기록하여 크기 팽창을 방지함
- 전처리 변환 수행: BWT(Burrows-Wheeler Transform)를 통해 동일 문자가 뭉치도록 데이터를 정렬한 뒤 RLE를 적용하여 압축률을 극대화함

## Ⅵ. 전망
- RLE 자체는 단순하지만, 딥러닝에서 희소 행렬(Sparse Matrix) 압축이나 팩스 표준, 비트맵 이미지 처리 등 연속성이 보장된 특정 영역에서 여전히 효율적인 전처리 수단으로 쓰임
