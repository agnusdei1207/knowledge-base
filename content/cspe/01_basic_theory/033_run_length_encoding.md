## 미리 알고가기

- 런: 같은 값이 연속해서 나타나는 구간임
- 무손실 압축: 복호 결과가 원본과 완전히 같은 압축 방식임
- 반복 길이: 하나의 런에 포함된 동일 기호의 개수임
- 이스케이프 부호: 압축 토큰과 원본 데이터를 구분하는 식별자임
- 스캔 순서: 데이터를 읽는 방향이며 연속 반복 길이에 직접 영향을 줌

## Ⅰ. 개요

- **정의/개념**: 런랭스 인코딩은 연속 반복 데이터를 값과 반복 횟수의 쌍으로 표현하는 무손실 압축 방식임
- **배경/필요성**: 반복 값이 많은 이미지·문서의 저장 크기를 줄이기 위해 반복 횟수 기반 부호화가 필요함

## Ⅱ. 특징

- 반복 구간이 길수록 압축률이 급격히 좋아짐
- 반복이 없으면 횟수 정보 때문에 오히려 데이터가 커짐
- 인코딩과 디코딩이 단순해 처리 지연이 작음
- 다른 압축 기법의 전처리 또는 후처리로 자주 결합됨

## Ⅲ. 종류 및 비교

| 구분 | RLE | 허프만 코딩 | 델타 코딩 |
|:---|:---|:---|:---|
| 압축 기준 | 동일 값의 연속 길이 | 기호별 발생 빈도 | 이전 값과의 차이 |
| 적합 데이터 | 팩스, 단색 비트맵 | 빈도 편중 텍스트 | 센서값, 시계열 |
| 강점 | 구현과 복호가 단순 | 일반 데이터에 고른 압축률 | 완만한 변화에 효과 |
| 약점 | 무작위 데이터에 취약 | 코드북 필요 | 급격한 변화에 취약 |

> 요약: RLE는 빈도보다 연속성이 높은 데이터에서 효과가 큼.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기호 | 반복 여부를 판단하는 실제 데이터 값임 |
| 카운터 | 현재 기호가 몇 번 이어졌는지 저장함 |
| 토큰 | 기호와 반복 횟수를 묶은 압축 단위임 |
| 이스케이프 | 짧은 반복과 원본 구간을 구분해 오버헤드를 줄임 |
| 출력 버퍼 | 생성된 토큰을 순서대로 저장함 |

```text
원본  : A A A A B B C D D D
런    : A4 B2 C1 D3
토큰  : (A,4) (B,2) (C,1) (D,3)
```

> 요약: RLE는 연속 구간을 값과 길이 토큰으로 바꿔 반복 저장을 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+   +----------+   +----------+   +----------+
| 값 읽기  | -> | 반복 계산 | -> | 토큰 출력 | -> | 다음 값 이동 |
+----------+   +----------+   +----------+   +----------+
```

1. 첫 기호를 기준값으로 두고 카운터를 1로 초기화함
2. 다음 기호가 같으면 카운터를 증가시킴
3. 값이 바뀌면 기준값과 카운터를 토큰으로 출력함
4. 새 기호를 기준값으로 바꾸고 끝까지 반복함

> 요약: 한 번의 순차 스캔에서 값 변화 시점마다 이전 런을 토큰으로 확정함.

## Ⅵ. 실무 적용 및 유의점

1. 자연 이미지처럼 값 변화가 잦은 데이터는 RLE 결과가 커질 수 있으므로 반복 길이 임계값과 원본 유지 조건을 둠
2. 비트맵·문서 이미지는 행 방향 반복이 길어야 하므로 스캔 순서와 전처리 후 압축률을 비교함

## Ⅶ. 결론

- 런랭스 인코딩은 데이터의 연속 반복성이 충분할 때 가장 단순한 구조로 높은 무손실 압축 효과를 내는 방식임

## 작성 근거(검토용)

- RLE 판단 기준은 빈도보다 연속성이므로 개요부터 결론까지 반복 길이에 일치시킴
- 비교표는 허프만과 델타를 두어 연속성, 빈도, 변화량이라는 압축 기준 차이를 보임
- 구조 절은 구현에 필요한 최소 상태인 기호, 카운터, 토큰을 중심으로 정리함
- 절차 절은 한 번의 순차 스캔으로 압축되는 단순성을 보여주도록 작성함
- 유의점은 압축 팽창과 스캔 순서로 제한해 실제 적용 실패 원인을 직접 다룸
