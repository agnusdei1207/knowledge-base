## Ⅰ. Overview

런랭스 인코딩($Run$-$Length$ $Encoding$, $RLE$)은 데이터 내에서 동일한 값이 연속해서 나타날 때, 이를 '값'과 '반복 횟수'의 쌍으로 치환하여 저장 공간을 줄이는 무손실 압축 기법임. 구현이 단순하고 연산 오버헤드가 극히 적어 실시간 처리에 최적화되어 있음.

### 가. 핵심 개념 정의
1.  **런 ($Run$):** 데이터 스트림에서 동일한 심볼이 중단 없이 연속적으로 나타나는 구간임.
2.  **런 길이 ($Run$ $Length$):** 하나의 런에 포함된 심볼의 개수($n$)임.
3.  **무손실성 ($Lossless$):** 압축 후 복원 시 원본 데이터와 비트 단위로 $100\%$ 일치함을 보장함.

## Ⅱ. Features

### 가. 무손실 압축 기법 간의 특성 비교

| 항목 | 런랭스 인코딩 ($RLE$) | 허프만 코딩 ($Huffman$) | $LZ$ 계열 ($Lempel$-$Ziv$) |
| :--- | :--- | :--- | :--- |
| **압축 원리** | 연속된 동일 값의 횟수 기록 | 심볼 출현 빈도 기반 가변 길이 할당 | 이전 문맥의 반복 패턴 참조 |
| **압축 이득 조건** | 긴 연속성($Run$)이 많을 때 | 특정 기호 확률 분포가 편중될 때 | 단어/문구 단위 반복이 많을 때 |
| **구현 난이도** | 매우 낮음 | 중간 | 높음 (사전 탐색 필요) |
| **복잡도 ($Time$)** | $O(N)$ (선형 시간) | $O(N \log N)$ (트리 구성) | $O(N \times Window$ $Size)$ |

### 나. RLE의 효율성 결정 요인
- **데이터의 국소성 ($Locality$):** 인접한 데이터 간의 상관관계가 높을수록 압축률이 지수적으로 상승함.
- **심볼의 크기:** 런 길이를 표현하는 비트 수($k$)에 따라 한 번에 표현 가능한 최대 런 길이($2^k - 1$)가 결정됨.

## Ⅲ. Architecture Insight

### 가. 데이터 변환 구조 및 메커니즘
원본 데이터 $S = \{A, A, A, A, B, B, C\}$가 주어졌을 때:
1.  **순수 페어링 ($Pairing$):** $(A, 4), (B, 2), (C, 1)$ 형태로 변환함.
2.  **이스케이프 방식 ($Escape$ $Sequence$):** 반복이 적은 구간의 오버헤드를 줄이기 위해, 특정 횟수 이상 반복될 때만 $[ESC][Value][Count]$ 형식을 사용함.

### 나. 전처리를 통한 효율 극대화 (Preprocessing Synergy)
- **Zig-zag Scan:** $JPEG$ 등에서 $2$차원 데이터를 $1$차원으로 나열할 때 $0$이 연속해서 나오도록 유도하여 $RLE$ 효율을 극대화함.
- **Delta Encoding:** 값 자체가 아닌 이전 값과의 차이($\Delta$)를 기록하여 $0$ 또는 동일한 값이 많이 발생하도록 유도함.

## Ⅳ. PPA & Trade-offs

### 가. PPA (Power, Performance, Area) 관점 분석
- **Power:** 연산이 단순 비교와 카운팅에 국한되어 $CPU/MCU$의 전력 소모가 매우 낮음.
- **Performance:** 초당 기가비트($Gbps$) 단위의 라인 속도($Line$ $Rate$)로 실시간 압축/복원이 가능함.
- **Area:** 별도의 사전($Dictionary$)이나 통계 테이블을 유지할 메모리가 거의 필요 없어 초소형 임베디드 칩셋에 적합함.

### 나. 주요 Trade-offs
- **Compression Ratio vs Data Randomness:** 데이터가 무작위($Random$)할 경우 오히려 데이터 크기가 $2$배로 늘어나는 압축 역전($Negative$ $Compression$)이 발생함.
- **Run Length bit-width:** 런 길이를 표현하는 비트가 너무 크면 작은 런에서 낭비가 발생하고, 너무 작으면 긴 런을 여러 번 나누어 기록해야 함.

## Ⅴ. Real-world Troubleshooting

### 가. 압축 역전 현상 (Expansion)
- **현상:** 반복이 없는 데이터(예: $1, 2, 3, 4$) 처리 시 데이터량이 증가함.
- **해결:** **리터럴 플래그($Literal$ $Flag$)**를 도입하여, 압축되지 않은 원본 구간임을 표시하고 해당 구간은 그대로 복사하는 하이브리드 방식을 적용함.

### 나. 데이터 오염의 파급 (Error Propagation)
- **현상:** 가변적인 런 길이 정보 비트가 깨지면, 이후 모든 데이터의 위치($Offset$)가 어긋나 복구가 불가능함.
- **해결:** 고정 크기 블록($Block$) 단위로 독립 압축하고, 블록 헤더에 $CRC$를 추가하여 오류를 검출하고 전파를 차단함.

## Ⅵ. Professional Insight

런랭스 인코딩은 가장 기초적인 알고리즘이지만, 데이터의 '물리적 연속성'을 공략하는 강력한 도구임. 기술사는 단순히 $RLE$ 단독 사용에 그치지 않고, **BWT($Burrows$-$Wheeler$ $Transform$)$**나 **Zig-zag Scan**과 같은 전처리 기법을 결합하여 데이터의 엔트로피를 인위적으로 낮춘 후 $RLE$를 적용하는 전략적 설계 역량을 보여야 함.

특히 현대의 컬럼형 데이터베이스($Parquet$, $ORC$)나 딥러닝 가중치 양자화($Pruning$) 이후의 희소 행렬($Sparse$ $Matrix$) 압축에서 $RLE$가 핵심적인 역할을 수행하고 있음을 이해하고, 시스템의 요구사항($PPA$)에 맞춰 최적의 런 길이 비트 폭을 결정할 수 있어야 함.
