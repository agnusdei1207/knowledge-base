## Ⅰ. 개요

- **정의**: 런랭스 인코딩(RLE, Run-Length Encoding)은 연속으로 반복되는 동일 값 구간(런, Run)을 (값, 반복 횟수) 쌍으로 치환하는 무손실 압축 기법임.
- **배경/필요성**: 흑백 팩스 문서·이진 이미지처럼 동일 값이 길게 이어지는 데이터를 원본 그대로 저장하면 같은 값을 매번 중복 기록하는 낭비가 발생하므로, 반복 구간 자체를 압축 단위로 삼는 방법이 필요함.
- **출제 의도**: 반복 길이 기반 압축 원리의 이해, 인코딩·디코딩 절차 구현력, 데이터 반복 특성에 따른 적용·역효과 판단력 확인.
- **답안 방향**: 구조(런 탐지·카운팅·디코딩) → 동작(구체 인코딩 예시와 역효과 조건) → 비교(허프만·LZ77 대비 선택 기준) → 실무 적용 순으로 전개함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 반복 기반 압축 기법 설명·비교 요구 | 런 탐지·인코딩 절차, 반복이 적을 때의 역효과, 허프만(빈도 기반)과의 원리 차이 | 반복 조건 없이 장점만 서술, 빈도 기반 기법과 원리 혼동 |

> 요약: RLE 답안은 "반복 길이"가 유일한 압축 근거임을 못박고, 반복이 적은 데이터에서의 역효과까지 함께 논증해야 함.

## Ⅱ. 구조 및 구성요소

```text
원본 스트림 -> 런 탐지(동일값 구간 식별) -> 카운팅(길이 누적) -> (값,길이) 쌍 출력 -> 압축 스트림
                                                                          |
                                                                          v
                                                                디코딩: 쌍마다 값을 길이만큼 복원
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| 런 탐지 | 인접 원소를 비교해 동일값 구간의 시작·끝 식별 | 같은 색 블록의 경계 찾기 |
| 카운터 | 런이 이어지는 동안 길이를 누적 | 몇 개가 이어지는지 세기 |
| `(값, 길이)` 쌍 | 인코딩 결과의 최소 단위 | "빨강 5개"라는 요약 |
| 디코더 | 각 쌍의 값을 길이만큼 반복 출력해 원본 복원 | 출석 부른 이름을 인원수만큼 되풀이 |

> 요약: 런 탐지와 카운팅이 압축 단위를 만들고, 디코더는 그 쌍을 역으로 풀어 원본을 그대로 복원함.

## Ⅲ. 동작원리 및 흐름도

```text
스캔 시작(기준값=첫 원소, count=1) -> 다음 원소 비교
  -> 기준값과 같음: count 증가, 스캔 계속
  -> 기준값과 다름: (기준값,count) 출력 -> 기준값 갱신, count=1
-> 입력 끝 도달 시 마지막 (기준값,count) 출력
```

- 1단계(초기화): 첫 원소를 기준값으로 설정하고 `count`를 1로 초기화함.
- 2단계(런 연장): 다음 원소가 기준값과 같으면 `count`를 증가시키며 스캔을 이어감.
- 3단계(런 종료): 원소가 바뀌면 현재까지의 `(기준값, count)` 쌍을 출력하고, 새 원소를 기준값으로 재설정함.
- 4단계(종료 처리): 입력 끝까지 반복한 뒤 마지막 런을 출력함. 디코딩은 각 쌍을 `count`만큼 값을 반복 출력하는 역순으로 수행함.

**인코딩 예시** — 입력 `AAAABBBCC` (9문자):

```text
스캔: A A A A | B B B | C C
런 1: A, count=4 -> "4A"
런 2: B, count=3 -> "3B"
런 3: C, count=2 -> "2C"

결과: "4A3B2C" (6문자, 원본 대비 33% 절감)
```

**역효과 예시** — 반복이 없는 입력 `ABCDE` (5문자):

```text
스캔: A | B | C | D | E   (모든 런 길이=1)
결과: "1A1B1C1D1E" (10문자, 오히려 원본의 2배로 증가)
```

> 요약: 런이 길수록 `(값,길이)` 쌍 하나가 여러 원소를 대체해 압축되지만, 런 길이가 1~2에 머물면 카운트 표기 자체가 오버헤드가 되어 원본보다 커짐.

## Ⅳ. 특징

- 반복 길이 의존성: 압축 효과가 오직 연속 반복 길이에 좌우됨. 허프만 코딩(032)처럼 전체 심볼의 출현 빈도 분포를 이용하는 것이 아니라, 인접 원소가 같은 값으로 몇 번 이어지는지만 봄.
- 구현 단순성: 힙·트리 같은 보조 자료구조 없이 선형 스캔만으로 동작하여 $O(N)$ 시간·공간에 구현됨.
- 역효과 조건: 런 길이가 짧은 데이터(자연 사진, 임의 텍스트)에서는 `(값,길이)` 표기 오버헤드로 오히려 크기가 증가함.
- 적용 도메인 편중: 값 도메인이 좁고 동일 값이 길게 이어지는 이진 이미지·팩스·스프라이트에 압축 효과가 집중됨.

> 요약: RLE의 압축 이득은 반복 길이에 정비례하므로, 데이터의 런 길이 분포를 먼저 확인한 뒤 적용해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 압축 근거 | RLE | 허프만 코딩 | LZ77 |
|:---|:---|:---|:---|
| 압축 원리 | 인접 동일값의 연속 길이 | 심볼 출현 빈도 분포 | 이전에 등장한 패턴과의 일치 |
| 최적 데이터 | 이진 이미지, 팩스, 스프라이트 | 빈도 편차가 큰 텍스트·코드 | 반복 패턴이 비연속적으로 산재한 범용 데이터 |
| 최악 상황 | 런 길이 1~2 연속 시 크기 증가 | 균등 분포 시 압축 이득 없음 | 반복 패턴 자체가 없으면 이득 미미 |
| 선택 기준 | 런 길이가 길고 값 도메인이 좁을 때 | 심볼 빈도 편차가 크고 순서 무관할 때 | 반복이 떨어져 있거나 순서 의존적일 때 |

> 요약: 데이터의 압축 근거가 "연속 반복"인지 "빈도 편차"인지 "산재 패턴"인지에 따라 세 기법의 선택이 갈림.

**리스크·대응 (불릿):**
- 런 길이 과소 데이터 적용: 반복이 짧은 데이터에 RLE를 그대로 적용하는 것이 원인 → 사전 런 길이 히스토그램 분석 후 적용 여부 판단으로 대응함.
- 단독 적용 한계: RLE 단독으로는 비반복 구간을 압축할 수 없는 것이 원인 → DCT·양자화 등 전처리로 반복 구간을 인위적으로 늘린 뒤 RLE를 적용(JPEG 방식)하는 방식으로 대응함.

**도입 후 점검 지표 (불릿):**
- 압축률: 원본 대비 인코딩 결과 크기 비율을 실측해 목표 압축률 충족 여부를 확인함.
- 런 길이 분포: 평균 런 길이가 임계값(예: 3) 미만인 구간 비율을 측정해 역효과 발생 가능성을 점검함.

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 데이터의 런 길이 분포를 분석해 RLE 적용 대상(이진 이미지·팩스 등)을 식별함.
2. 중기: JPEG의 지그재그 스캔+RLE+허프만처럼, 반복이 적은 데이터는 전처리로 런을 인위적으로 늘린 뒤 RLE를 적용하는 파이프라인을 구성함.
3. 장기: 컬럼 스토어(Parquet 등)처럼 정렬된 데이터에 RLE를 상시 적용하는 저장 계층 정책으로 확장함.

- 기술사적 판단: 런 길이가 충분히 길 때만 RLE를 단독 적용하고, 그렇지 않으면 다른 압축 기법과 조합하거나 배제함.
- 기술사 제언: RLE는 무손실 압축(034 소스 코딩)의 한 방법이며 채널 코딩과는 무관하므로, 오류 정정 목적으로 혼용하지 않도록 구분함.
