# 런랭스 인코딩 (Run-Length Encoding)

## 1. 개요

- **정의/개념**: 런랭스 인코딩(Run-Length Encoding, RLE)은 같은 값이 연속해서 반복되는 구간을 값과 반복 횟수의 쌍으로 표현하는 무손실 압축 방식이다.
- **배경/필요성**: 이미지 마스크, 팩스, 로그처럼 동일 값이 길게 반복되는 데이터는 원본을 그대로 저장하면 중복이 크므로 반복 길이를 기록하는 방식이 효율적이다.

RLE는 반복 구간이 길수록 효과적이고, 반복이 적으면 오히려 데이터가 커질 수 있다는 조건부 압축이다.

## 2. 특징 및 비교

| 구분 | RLE | 허프만 코딩 | LZ 계열 |
|---|---|---|---|
| 압축 기준 | 연속 반복 길이 | 기호 빈도 | 이전 문자열 참조 |
| 강점 | 구현 단순, 빠름 | 빈도 편향에 강함 | 반복 패턴 일반화 |
| 약점 | 반복 없으면 비효율 | 코드표 필요 | 사전·윈도우 관리 |
| 적합 데이터 | 단색 이미지, 마스크 | 편향된 텍스트·계수 | 일반 파일 압축 |

RLE 선택 기준은 연속 반복성, 인코딩 오버헤드, 실시간 처리 요구, 다른 압축과의 결합 가능성이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Symbol | 반복되는 값 | 압축 단위 |
| Run | 동일 값의 연속 구간 | 압축 이득 발생 |
| Count | 반복 횟수 | 길이 표현 범위 |
| Escape Rule | 값과 카운트 구분 규칙 | 복호 모호성 제거 |
| Block Boundary | 압축 단위 경계 | 오류 영향 제한 |

```text
AAAAABBBCCDAA -> (A,5)(B,3)(C,2)(D,1)(A,2)
```

반복 구간을 정확히 식별해야 복호 시 원본 길이와 값 순서를 그대로 복원할 수 있다.

## 4. 문제점 및 개선방안

1. **압축률 역전**
   - 반복이 적은 데이터에서는 값과 횟수 저장 오버헤드로 크기가 증가한다.
   - **개선방안**: 최소 run 길이 기준, 압축 여부 플래그, hybrid 압축을 적용한다.

2. **Count 범위 제한**
   - 반복 길이가 표현 가능한 최대 count를 넘으면 복호가 틀어질 수 있다.
   - **개선방안**: 긴 run 분할, variable-length count를 사용한다.

3. **오류 전파**
   - count 값이 손상되면 이후 데이터 위치 해석이 달라진다.
   - **개선방안**: 블록 단위 압축, checksum, 길이 검증을 적용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 이미지 마스크 | 동일 픽셀 구간을 값·길이로 압축 | 압축률, 복호 시간 |
| 팩스·스캔 데이터 | 흑백 연속 구간을 run으로 표현 | 전송량, 오류율 |
| 컬럼 저장소 | 동일 값이 연속되는 컬럼 데이터를 압축 | 저장률, scan 성능 |

## 6. 결론

RLE는 반복 구간이 뚜렷한 데이터에서 매우 단순하고 빠른 무손실 압축 방식이다. 반복성, count 오버헤드, 오류 전파를 함께 판단해야 허프만·LZ 계열과의 선택 기준이 분명해진다.
