## 미리 알고가기

- run: 동일 값이 연속해서 반복되는 구간임
- 무손실 압축: 원본을 정확히 복원하는 압축 방식임
- sparse pattern: 값이 반복되거나 변동이 적은 데이터 특성임

## Ⅰ. 개요

- **정의/개념**: 런랭스 인코딩은 같은 값이 연속된 구간을 값과 반복 횟수의 쌍으로 치환해 저장하는 가장 단순한 무손실 압축 방식임
- **배경/필요성**: 흑백 이미지, 팩스, 마스크 데이터처럼 반복 구간이 긴 데이터는 원시 저장보다 훨씬 적은 공간으로 표현할 수 있음

## Ⅱ. 특징

- 구현이 매우 단순해 인코딩과 디코딩 비용이 낮음
- 긴 반복 구간이 많은 데이터에서 높은 압축 효율을 보임
- 반복이 적은 데이터에서는 오히려 크기가 커질 수 있음
- 다른 압축 기법의 전처리 단계로 자주 사용됨

## Ⅲ. 종류 및 비교

| 판단 기준 | RLE | Huffman | LZ 계열 |
|:---|:---|:---|:---|
| 압축 기준 | 연속 반복 | 빈도 분포 | 부분 문자열 재사용 |
| 구현 복잡도 | 매우 낮음 | 낮음 | 중간 |
| 강한 데이터 패턴 | 긴 run | 기호 편향 | 반복 구간 전반 |
| 약한 데이터 패턴 | 랜덤 데이터 | 균등 분포 | 짧은 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 현재 값 | 반복 기준 값이며 run 시작을 결정함 |
| 카운터 | 연속 반복 횟수를 셈 압축 단위를 형성함 |
| 출력 쌍 | 값과 길이를 기록하고 저장 형식 그 자체임 |
| 종료 조건 | 값 변경 또는 입력 종료이며 run 분할 시점임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 값읽기 | --> | 반복계수 | --> | 쌍출력 | --> | 다음구간 |
+----------+     +----------+     +----------+     +----------+
```

1. **값읽기**: 현재 기호를 기준값으로 잡음
2. **반복계수**: 동일 값이 연속되는 길이를 셈
3. **쌍출력**: `(값, 길이)` 형태로 기록함
4. **다음구간**: 다른 값이 나오면 새 run을 시작함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 반복이 적은 데이터에서 팽창해 길이 정보가 오히려 오버헤드가 됨
   - 해결방안: 적용 전 run 길이 통계를 보고 조건부 사용하고 압축률로 검증함
2. 문제: 최대 길이 표현 한계가 있어 카운터 비트 수를 넘는 긴 run은 분할해야 함
   - 해결방안: escape code나 가변 길이 카운터를 사용하고 인코딩 실패율로 검증함
3. 문제: 값 경계 손상 시 복구가 어려워 한 쌍 오류가 뒤 구간 해석을 흐릴 수 있음
   - 해결방안: 블록 단위 checksum과 재동기화 마커를 추가하고 복구 성공률로 검증함

## Ⅶ. 적용 사례

- 흑백 이미지/팩스에서는 긴 동일 픽셀 구간을 짧게 저장함, 확인 지표는 전송 비트 수임
- 비트맵 마스크/아이콘에서는 단순 반복 패턴을 압축함, 확인 지표는 메모리 사용량임
- 센서 상태 로그에서는 동일 상태 연속 구간을 요약함, 확인 지표는 저장 공간 절감률임

## Ⅷ. 결론

RLE는 반복 구간이 길수록 강력하고 그렇지 않으면 손해가 나므로, 적용 전 데이터의 run 분포를 먼저 판단하는 것이 핵심임.
