## Ⅰ. 개요
- **정의**: 연속 반복 데이터를 (심볼, 반복 횟수) 쌍으로 치환하는 무손실 압축 기법
- **배경/필요성**: 팩시밀리·BMP 등 연속 동일 값이 빈번한 데이터에서 간단한 구현으로 높은 압축비를 달성할 필요가 있음
- **비유**: "AAABB" → "A3B2"처럼, 같은 글자가 몇 번 반복되는지 세어 기록하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 단순 압축 원리 이해 | 반복 구간이 길수록 압축비 증가 | 반복이 적으면 오히려 팽창(역효과)함을 언급 |
| 허프만 등 타 기법과 비교 | RLE는 공간적 중복, 허프만은 통계적 중복 대상 | 032 허프만과 원리적 차이를 명확히 구분 |

> 요약: 연속 반복 심볼을 (값, 횟수)로 치환하는 가장 단순한 무손실 압축 기법임.

## Ⅱ. 구성요소
```text
+----------+     +----------+     +----------+
| 입력     | --> | 반복탐색  | --> | 인코딩   |
| 스트림   |     | (Run감지) |     | (값,횟수) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Run(반복 구간) | 동일 심볼이 연속 출현하는 구간, 길이가 압축비를 결정함 | 같은 색 타일이 이어진 줄 |
| 카운터 | 반복 횟수를 기록하는 필드로, 고정 비트폭(8bit=최대 255) 사용 | 타일 개수 세기 |
| 이스케이프/플래그 | 비반복 구간과 반복 구간을 구분하는 제어 바이트 | 구간 경계 표지판 |

> 요약: Run 감지 → 카운터 기록 → 플래그 삽입으로 반복 구간을 압축함.

## Ⅲ. 절차
```text
+------------+     +------------+
| 심볼읽기   | --> | Run길이    |
| (순차스캔) |     | 카운팅     |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 출력완료   | <-- | (값,횟수)  |
| (압축결과) |     | 기록       |
+------------+     +------------+
```

1. **심볼 읽기** — 입력 스트림을 순차적으로 스캔하여 현재 심볼을 확인함
2. **Run 길이 카운팅** — 현재 심볼과 동일한 연속 심볼 수를 카운팅함(최대 카운터 비트폭까지)
3. **(값, 횟수) 기록** — 심볼 값과 반복 횟수를 출력 스트림에 기록함
4. **반복/종료** — 입력 종료까지 1~3을 반복하고, 비반복 구간은 리터럴로 기록함

> 요약: 순차 스캔 → Run 카운팅 → 쌍 기록 → 반복으로 압축을 수행함.

## Ⅳ. 문제점
- [팽창 문제]: 반복이 적은 데이터(텍스트 등)에서 원본보다 크기가 증가함 — 카운터 오버헤드 때문
- [카운터 오버플로]: 고정 비트폭 카운터로 긴 Run을 한 번에 표현 못 함 — 분할 인코딩 필요
- [복합 데이터 부적합]: 자연 이미지·음성 등 연속 반복이 드문 데이터에서 압축비가 1 미만임

> 요약: 반복이 적으면 팽창하고, 카운터 제약과 복합 데이터 부적합이 주요 한계임.

## Ⅴ. 개선방안
1. 단기: PackBits 방식으로 리터럴/반복을 플래그로 구분하여 비반복 구간 팽창을 방지함
2. 중기: RLE + 허프만(DEFLATE 내부)처럼 다단계 파이프라인으로 통계적 중복까지 제거함
3. 장기: 컨텍스트 기반 예측 + 잔차 RLE(PNG 필터 등)로 자연 이미지에도 적용 가능하게 확장함

- [팽창 문제]: 비반복 빈발 → PackBits 리터럴 모드 (지표: 압축비 ≥ 1.0 보장)
- [카운터 오버플로]: 고정폭 한계 → 가변 길이 카운터 또는 연속 분할 인코딩 (지표: Run 최대 길이 무제한)
- [복합 데이터 부적합]: 원시 적용 한계 → 전처리(델타, BWT) 후 RLE 적용 (지표: 텍스트 압축비 1.5× 이상)

> 요약: PackBits로 팽창 방지, 다단계 파이프라인으로 적용 범위를 확장함.

## Ⅵ. 전망
- 향후 발전 방향: PCX·BMP·TIFF 등 레거시 포맷에서 여전히 사용되며, PNG 필터·JPEG-LS의 전처리 단계로 RLE가 내장됨
- 기술사적 판단: 단독 압축 기법으로는 한계가 분명하나, 파이프라인의 1차 전처리기로서 가치가 지속됨
- 기술사 제언: 032 허프만·산술 코딩과 결합한 다단계 압축 설계에서 RLE의 역할을 명확히 정의해야 함
