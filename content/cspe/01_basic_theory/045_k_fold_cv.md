## 미리 알고가기

- 일반화 성능($Generalization$): 학습에 사용되지 않은 새로운 데이터에 대해 모델이 얼마나 잘 예측하는지를 나타내는 능력임
- 홀드아웃($Hold-out$): 데이터를 단순히 훈련셋과 테스트셋으로 한 번만 나누어 평가하는 방식임
- 폴드($Fold$): 전체 데이터를 $K$개의 동일한 크기로 나눈 부분 집합 중 하나임
- 데이터 누수($Data$ $Leakage$): 테스트 데이터의 정보가 학습 과정에 포함되어 성능이 비정상적으로 높게 나오는 현상임

## Ⅰ. 개요

- **정의/개념**: K-Fold 교차 검증은 전체 데이터를 $K$개의 그룹으로 나눈 후, 매번 다른 한 그룹을 검증셋으로 사용하고 나머지 $K-1$개 그룹을 훈련셋으로 활용하여 총 $K$번 학습과 평가를 반복하는 모델 검증 기법임
- **배경/필요성**: 데이터셋의 크기가 작을 때 한 번의 홀드아웃 분할만으로는 평가 결과의 편차가 커서 모델의 진정한 성능을 신뢰하기 어렵기 때문에, 모든 데이터를 학습과 검증에 골고루 활용하기 위해 도입됨

## Ⅱ. 특징

- 모든 데이터 포인트를 최소 한 번씩은 검증에 사용하므로 특정 데이터 분할에 따른 성능 왜곡(샘플링 편향)을 최소화하고 모델의 '안정성'을 확보할 수 있음
- 반복된 검증 결과의 평균과 표준편차를 분석함으로써, 모델의 예측력이 얼마나 일관된지(분산)와 실제 성능 수준(편향)을 정밀하게 진단 가능함
- 하이퍼파라미터 튜닝 시 최적의 설정을 찾는 기준($Internal$ $Validation$)으로 활용되며, 데이터가 부족한 환경에서 성능 평가의 통계적 유의성을 높임

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 홀드아웃 (Hold-out) | K-Fold 교차 검증 | Stratified K-Fold |
|:---|:---|:---|:---|
| **평가 횟수** | 1회 | $K$회 | $K$회 |
| **데이터 활용** | 고정된 분할만 사용 | 모든 데이터 활용 | 클래스 비율 유지하며 활용 |
| **계산 비용** | 매우 낮음 | 높음 ($K$배 증가) | 높음 ($K$배 증가) |
| **적합 데이터** | 대용량 데이터셋 | 중소규모 데이터셋 | 불균형 데이터셋 (분류) |

> 요약: 홀드아웃은 속도가 빠르고, K-Fold는 평가의 신뢰도가 높으며, Stratified는 비율 유지에 강점이 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 훈련 세트 ($Train$) | 모델의 가중치를 업데이트하기 위해 실제 학습에 투입되는 $K-1$개의 폴드임 |
| 검증 세트 ($Val$) | 학습된 모델의 성능을 측정하고 과적합 여부를 판단하기 위한 1개의 폴드임 |
| 셔플링 ($Shuffling$) | 데이터를 나누기 전 순서를 무작위로 섞어 데이터 배열 순서에 의한 편향을 방지함 |
| 최종 성능 지표 | $K$개 테스트 결과의 산술 평균값으로, 모델의 일반화 성능으로 간주함 |

```text
Iter 2: [Tr ] [Val] [Tr ] [Tr ] [Tr ]
...
Iter 5: [Tr ] [Tr ] [Tr ] [Tr ] [Val]
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 전체 데이터 셔플| --> | K개 폴드 분할 | --> | K회 학습/평가 루프| --> | 평균 성능 산출|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **폴드 분할** — 전체 데이터셋을 무작위로 섞은 뒤, 사용자 정의 상수 $K$(주로 5 또는 10)만큼의 동일한 크기 덩어리로 나눔
2. **반복 학습** — 첫 번째 폴드를 제외한 나머지 데이터로 모델을 학습시키고, 남겨둔 첫 번째 폴드로 예측 성능을 기록함
3. **교차 수행** — 검증 폴드의 위치를 다음 번호로 옮겨가며 전체 폴드가 한 번씩 검증셋이 될 때까지 학습 과정을 되풀이함
4. **결과 집계** — $K$번의 반복 수행에서 얻은 개별 성능 점수들의 평균과 분산을 계산하여, 모델의 최종 성능 지표로 확정함

## Ⅵ. 실무 적용 및 유의점

1. 데이터 스케일링이나 특징 추출 등 전처리 과정을 교차 검증 전에 전체 데이터를 대상으로 수행하면 테스트 정보가 학습에 스며드는 '데이터 누수'가 발생하므로, 반드시 각 폴드 루프 안에서 전처리가 독립적으로 수행되도록 '파이프라인($Pipeline$)' 설계를 해야 함
2. 시계열 데이터($Time-series$)의 경우 과거 데이터로 미래를 예측해야 하는 시간적 순서가 중요하므로, 무작위 분할인 K-Fold 대신 과거 구간을 늘려가며 다음 구간을 검증하는 '시계열 교차 검증($TimeSeriesSplit$)'을 적용해야 함

## Ⅶ. 결론

- K-Fold 교차 검증은 모델의 일반화 성능을 객관적으로 입증하기 위한 통계적 방패이며, 설계자는 계산 비용과 평가의 정밀도 사이의 균형을 고려하여 최적의 $K$ 값을 설정하고 데이터 누수 없는 엄격한 검증 환경을 구축해야 함
