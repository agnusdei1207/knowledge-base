## 미리 알고가기

- 폴드: 전체 데이터를 나눈 부분집합이며 검증 또는 학습에 번갈아 사용함
- Hold-out: 데이터를 한 번만 학습용과 검증용으로 나누는 평가 방식임
- Stratified K-Fold: 클래스 비율을 각 폴드에 유지하는 교차 검증 방식임
- 데이터 누수: 검증 데이터 정보가 학습 과정에 섞여 성능이 과대평가되는 문제임
- 일반화 성능: 보지 않은 데이터에 대해 모델이 유지하는 예측 성능임

## Ⅰ. 개요

- **정의**: K-Fold 교차 검증은 데이터를 `K`개 폴드로 나누고 매번 하나의 폴드를 검증에 사용해 `K`회 성능을 평균함으로써 모델의 일반화 성능을 추정하는 평가 절차임
- **배경/필요성**: 단일 Hold-out 분할은 우연한 데이터 배치에 따라 성능 추정이 흔들릴 수 있으므로 제한된 데이터를 여러 번 검증에 활용할 기준이 필요함
- **비유**: 문제지를 여러 묶음으로 나누고 매번 다른 묶음을 모의고사로 사용해 평균 실력을 확인하는 방식과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 평가 설계 이해 | K-1 학습, 1 검증, K회 반복 | 검증 데이터를 학습에 사용 |
| 일반화 성능 추정 | 평균 성능, 분산, 폴드 안정성 | 시계열·불균형 데이터 분할 기준 누락 |

> 요약: K-Fold는 데이터 분할 운에 의한 평가 왜곡을 줄이기 위해 검증 역할을 여러 폴드에 순환시키는 방법임.

## Ⅱ. 특징/비교

| 판단 기준 | Hold-out·LOOCV | K-Fold 교차 검증 |
|:---|:---|:---|
| 평가 안정성 | Hold-out은 빠르지만 분할 운에 민감하고 LOOCV는 분산이 클 수 있음 | 여러 검증 결과 평균으로 안정성을 높임 |
| 계산 비용 | Hold-out은 1회 학습, LOOCV는 데이터 수만큼 학습함 | `K`회 학습으로 비용과 안정성의 균형을 잡음 |
| 데이터 활용 | 검증에 쓰이지 않는 데이터가 있거나 한 샘플 단위 평가가 됨 | 모든 데이터가 학습과 검증에 번갈아 참여함 |
| 선택 조건 | 데이터가 충분하거나 빠른 기준선 평가에 적합함 | 데이터가 제한되고 성능 추정 신뢰도가 중요할 때 적합함 |

> 요약: K-Fold는 계산 비용을 감수하고도 분할 편향을 줄여야 할 때 선택하는 균형형 검증 방식임.

- **입력 조건**: 데이터가 폴드 간 독립성을 유지할 수 있는 구조인지 먼저 확인해야 함
- **평가 기준**: 평균 성능뿐 아니라 폴드별 분산과 최악 성능을 함께 봄
- **선택 판단**: 데이터가 제한되고 단일 분할 신뢰도가 낮을 때 우선 적용함

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| 전체 데이터 | ---> | K개 폴드    | ---> | K회 학습·검증 |
+------------+      +------------+      +------------+
       |                  |                  |
       v                  v                  v
+------------+      +------------+      +------------+
| 분할 정책   |      | 성능 지표   |      | 평균·분산   |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 전체 데이터 | 학습과 검증에 순환 사용할 원천 데이터이며 중복·누수 여부를 먼저 확인함 | 전체 문제집 |
| 분할 정책 | 무작위, 층화, 그룹, 시계열 순서 등 데이터 특성에 맞는 폴드 생성 규칙임 | 시험 범위 나누기 |
| 학습·검증 반복 | 매 반복에서 K-1개 폴드로 학습하고 1개 폴드로 성능을 측정함 | 번갈아 보는 모의고사 |
| 성능 지표 | 정확도, F1, AUC, RMSE 등 문제 목적에 맞는 평가 기준임 | 채점 기준 |
| 평균·분산 | 폴드별 결과를 종합해 성능 수준과 변동성을 함께 판단함 | 성적 평균과 편차 |

> 요약: K-Fold는 폴드 생성 정책, 반복 학습, 성능 지표, 평균·분산 해석이 함께 맞아야 신뢰할 수 있음.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| 분할 설계   | ---> | 반복 학습   | ---> | 성능 집계   | ---> | 모델 선택   |
+------------+      +------------+      +------------+      +------------+
```

1. **분할 설계**: 데이터 독립성, 클래스 비율, 그룹, 시간 순서를 고려해 폴드 생성 방식을 정함
2. **반복 학습**: 각 반복에서 검증 폴드를 제외한 데이터로 전처리와 모델 학습을 수행함
3. **성능 측정**: 제외된 검증 폴드로 동일 지표를 계산하고 폴드별 결과를 기록함
4. **집계·선택**: 평균, 표준편차, 최악 폴드 성능을 보고 모델과 하이퍼파라미터를 선택함

> 요약: K-Fold 절차는 분할 정책을 먼저 확정하고 학습·검증을 반복한 뒤 평균과 변동성으로 모델을 판단하는 흐름임.

- **산출물**: 폴드별 성능, 평균·표준편차, 선택 모델과 하이퍼파라미터임
- **검증 기준**: 누수 없이 동일 파이프라인이 각 폴드에서 반복되어야 함
- **운영 기록**: 분할 seed, 폴드 정책, 전처리 fit 범위를 실험 로그에 남겨야 함

## Ⅴ. 문제점

- **P1 데이터 누수**: 전체 데이터로 전처리나 특징 선택을 먼저 수행하면 검증 폴드 정보가 학습에 섞여 성능이 과대평가됨
- **P2 비독립 데이터 부적합**: 시계열, 사용자별 반복 측정, 동일 장비 로그는 무작위 폴드가 미래 정보나 동일 그룹 정보를 누수시킬 수 있음
- **P3 계산 비용 증가**: 큰 모델이나 대규모 데이터에서는 `K`회 학습이 탐색 시간과 자원 비용을 크게 늘림

> 요약: K-Fold의 핵심 문제는 폴드 독립성이 깨지거나 반복 학습 비용이 커질 때 평가 신뢰도가 낮아진다는 점임.

## Ⅵ. 개선방안

- **P1 대응**: 전처리, 특징 선택, 스케일링을 각 학습 폴드 내부 파이프라인으로 수행함 (확인: 검증 폴드가 fit 단계에 미사용)
- **P2 대응**: TimeSeriesSplit, GroupKFold, Stratified K-Fold처럼 데이터 구조에 맞는 분할 방식을 적용함 (확인: 시간 역전과 그룹 중복 없음)
- **P3 대응**: 후보 모델을 사전 축소하고 병렬 학습, 조기 종료, nested CV 범위 제한을 적용함 (확인: 평가 시간과 성능 분산 기록)

> 요약: K-Fold 개선은 전처리 누수를 차단하고 데이터 의존 구조에 맞는 폴드 정책을 선택하는 것에서 시작함.

- **우선순위**: 데이터 누수와 그룹·시간 의존성 여부를 가장 먼저 점검함
- **확인 지표**: 폴드별 평균, 표준편차, 최악 폴드 성능을 함께 사용함
- **재평가 조건**: 데이터 수집 기간, 클래스 비율, 그룹 구조가 바뀌면 분할 방식을 재검토함

## Ⅶ. 전망

- **발전 방향**: K-Fold는 머신러닝 모델 비교, 하이퍼파라미터 튜닝, 논문·PoC 성능 검증에서 기본 평가 방법으로 계속 쓰일 것임
- **기술사적 판단**: 기술사는 평균 성능 하나보다 분할 정책, 누수 방지, 폴드별 성능 편차가 운영 환경을 대표하는지 확인해야 함
- **기술사 제언**: 향후 교차 검증은 자동화된 ML 파이프라인, 데이터 버전 관리, 재현성 추적과 결합해 모델 거버넌스의 평가 증거로 활용될 것임
