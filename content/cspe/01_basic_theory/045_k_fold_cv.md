# 교차 검증 K-Fold (Cross Validation K-Fold)

## 1. 개요

- **정의/개념**: K-Fold 교차 검증은 데이터를 K개 fold로 나누고 각 fold를 한 번씩 검증 데이터로 사용해 모델 성능을 평균적으로 평가하는 방법이다.
- **배경/필요성**: 단일 train/test 분할은 표본 선택에 따라 성능 추정이 흔들릴 수 있으므로, 여러 분할을 반복해 일반화 성능을 안정적으로 추정할 필요가 있다.

K-Fold의 핵심은 모델을 더 좋게 만드는 기법이 아니라 성능 추정의 분산을 줄이는 평가 절차라는 점이다.

## 2. 특징 및 비교

| 구분 | Hold-out | K-Fold | Stratified K-Fold |
|---|---|---|---|
| 방식 | 한 번 분할 | K번 반복 평가 | 클래스 비율 유지 |
| 장점 | 빠르고 단순 | 안정적 성능 추정 | 불균형 분류에 적합 |
| 단점 | 분할 운 영향 | 계산 비용 증가 | 구현 주의 필요 |
| 적용 | 대용량 데이터 | 중소 규모 데이터 | 분류 문제 |

선택 기준은 데이터 크기, 클래스 불균형, 시간 순서, 계산 비용, 데이터 누수 위험이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Dataset | 전체 학습 데이터 | 분할 대상 |
| Fold | K개의 부분 집합 | 검증 순환 |
| Train Split | K-1개 fold | 모델 학습 |
| Validation Split | 1개 fold | 성능 평가 |
| Average Metric | K번 결과 평균·분산 | 일반화 추정 |

```text
+----------+      +----------+      +----------+      +----------+
| K개분할  | ---> | K번학습  | ---> | K번평가  | ---> | 평균/분산 |
+----------+      +----------+      +----------+      +----------+
```

평가 절차가 데이터 누수를 만들면 평균 성능이 아무리 안정적이어도 실제 일반화 성능을 설명하지 못한다.

## 4. 문제점 및 개선방안

1. **데이터 누수**
   - 스케일링, 특징 선택을 전체 데이터에 먼저 적용하면 검증 fold 정보가 학습에 섞인다.
   - **개선방안**: 전처리를 fold 내부 pipeline으로 수행한다.

2. **시계열 데이터 오적용**
   - 시간 순서가 있는 데이터에 무작위 K-Fold를 쓰면 미래 정보가 과거 학습에 들어간다.
   - **개선방안**: time series split, rolling validation을 적용한다.

3. **불균형 데이터 편향**
   - 일부 fold에 소수 클래스가 거의 없으면 성능 추정이 왜곡된다.
   - **개선방안**: stratified split과 적절한 평가 지표를 사용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 모델 선택 | 후보 모델의 K-Fold 평균 성능 비교 | 평균 점수, 표준편차 |
| 하이퍼파라미터 튜닝 | 각 파라미터 조합을 교차 검증으로 평가 | validation score |
| 불균형 분류 | stratified K-Fold로 클래스 비율 유지 | F1, AUC |

## 6. 결론

K-Fold 교차 검증은 제한된 데이터에서 일반화 성능을 안정적으로 추정하는 평가 방법이다. 분할 방식, 전처리 위치, 데이터 누수, 시간 순서 조건이 맞아야 평균 성능이 신뢰 가능한 판단 근거가 된다.
