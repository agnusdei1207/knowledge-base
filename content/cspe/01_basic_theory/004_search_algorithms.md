## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 대규모 데이터 집합에서 특정 조건에 부합하는 항목을 효율적으로 찾아내는 알고리즘 기법임 |
| **배경/필요성** | 데이터베이스 조회, 정보 검색 시스템 등에서 응답 속도를 개선하고 자원 소모를 최소화하기 위함 |
| **출제 의도** | 이진 탐색의 분할 로직과 해시의 매핑 메커니즘을 이해하고, 탐색 성능 최적화 능력을 평가함 |

+-------------------+      +-------------------+

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 검색 공간 | 탐색의 대상이 되는 전체 데이터 범위 또는 배열임 | 도서관의 전체 서가 |
| 분할 포인터 | 이진 탐색에서 공간을 반으로 나누는 중간 인덱스임 | 사전의 중간 페이지 펴기 |
| 해시 함수 | 키 값을 고정된 크기의 주소(인덱스)로 변환하는 함수임 | 도서 분류 기호 체계 |

> 요약: 탐색은 정렬된 공간에서 포인터로 분할하거나, 해시 함수를 통해 직접 인덱스에 접근하여 수행됨.

## Ⅲ. 절차
+-------------------+      +-------------------+
|      Step 1       | ---> |      Step 2       |
+-------------------+      +-------------------+
                                     |
+-------------------+      +---------+---------+
|      Step 4       | <--- |      Step 3       |

1. 사전 조건 확인: 이진 탐색을 위한 정렬 여부 또는 해시 테이블 구성을 점검함
2. 키 매핑 및 분할: 해시 함수로 인덱스를 계산하거나 중간 인덱스를 도출함
3. 값 비교 및 분기: 타겟 값과 현재 값을 비교하여 탐색 방향을 결정함
4. 결과 반환: 값을 찾으면 위치를 반환하고, 없으면 실패 처리함

> 요약: 사전 구조화, 키 매핑 또는 범위 분할, 값 비교 분기, 최종 결과 반환의 절차로 진행됨.

## Ⅳ. 문제점
- 이진 탐색 제약: 데이터가 반드시 사전 정렬되어야 하므로 삽입/삭제가 빈번한 환경에서 비효율적
- 해시 충돌: 서로 다른 키가 동일한 해시 값을 가져 인덱스가 겹치는 해시 충돌(Collision) 발생
- 공간 낭비: 해시 충돌을 줄이기 위해 실제 데이터보다 훨씬 큰 해시 테이블 공간이 요구됨

## Ⅴ. 개선방안
- (단기) 체이닝/개방주소법: 해시 충돌 발생 시 연결 리스트나 선형 탐사로 충돌을 해결함
- (중기) 균형 이진 탐색 트리: 삽입/삭제 탐색이 모두 O(log N)을 보장하는 구조(AVL 등)로 전환함
- (장기) 동적 해싱 적용: 데이터 양에 따라 해시 테이블 크기를 자동 조절하는 확장 해싱 도입

## Ⅵ. 전망
- 머신러닝 기반 학습 인덱스(Learned Index)를 활용하여 탐색 공간을 예측하는 기술이 확산될 것임
