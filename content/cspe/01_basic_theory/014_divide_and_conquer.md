# 014. 분할 정복 (Divide and Conquer)

## 미리 알고가기

- **재귀 (Recursion)**: 큰 문제를 해결하기 위해 자신과 동일한 구조의 더 작은 문제를 호출하는 방식임
- **기저 조건 (Base Case)**: 재귀 호출을 멈추고 직접 답을 반환하는 최소 단위의 문제 상태임
- **독립성 (Independence)**: 분할된 부분 문제들이 서로 영향을 주고받지 않아 결과 결합 시 추가 고려사항이 적은 성질임

## 1. 개요

- **정의/개념**: 분할 정복(Divide and Conquer)은 방대한 문제를 직접 해결하기 쉬운 크기의 부분 문제로 나누고(Divide), 각 문제를 해결한 뒤(Conquer), 그 결과들을 합쳐(Combine) 원래 문제의 해를 구하는 알고리즘 설계 패러다임임
- **배경/필요성**: 데이터 규모 $n$에 대해 $O(n^2)$의 복잡도를 갖는 문제들을 절반씩 쪼개어 해결함으로써 단계를 $\log n$으로 축소하고, 전체 복잡도를 $O(n \log n)$ 수준으로 개선하여 시스템의 확장성을 확보하기 위해 사용함

## 2. 특징 및 비교

분할 정복은 문제를 나누는 방식과 부분 문제 간의 관계에 따라 동적 계획법(DP), 탐욕법(Greedy)과 구별됨.

| 비교 항목 | 분할 정복 (D&C) | 동적 계획법 (DP) | 탐욕 알고리즘 (Greedy) |
|:---|:---|:---|:---|
| **부분 문제 관계** | **서로 독립적 (Overlap 없음)** | 중복 발생 (Overlapping) | 해당 없음 |
| **핵심 기제** | 재귀적 구조 활용 | 메모이제이션/타뷸레이션 | 국소 최적해 선택 |
| **하향/상향** | 하향식 (Top-down) 위주 | 하향식/상향식 모두 활용 | 해당 없음 |
| **결합 과정** | **필수적 (Combine 단계)** | 필수적 (점화식 전이) | 불필요 (선택의 누적) |
| **대표 예시** | 병합/퀵 정렬, 이진 탐색 | LCS, 배낭 문제 | 최소 신장 트리, 허프만 코딩 |

> 요약: 부분 문제가 겹치지 않고 독립적일 때는 분할 정복이 명쾌하며, 중복이 발생하면 DP로 전환해야 함.

## 3. 구성요소/구조

분할 정복은 '분할-정복-결합'의 3단계 순환 구조를 가지며, 성능은 마스터 정리(Master Theorem)로 분석됨.

- **구성요소**:
  - **Divide**: 문제를 동일한 유형의 작은 부분 문제들로 나눔
  - **Conquer**: 하위 문제를 재귀적으로 해결함. 크기가 충분히 작으면 기저 조건에서 즉시 해결
  - **Combine**: 해결된 부분 문제의 답을 병합하여 상위 문제의 답 도출
  - **Recurrence**: 전체 수행 시간을 나타내는 점화식 ($T(n) = aT(n/b) + f(n)$)

- **알고리즘 처리 구조 (원리/흐름도)**:

```text
[Divide and Conquer Flow]
      [ Original Problem (size n) ]
             /            \                 -- Divide
    [ Sub-1 (n/2) ]    [ Sub-2 (n/2) ]
       /      \           /      \          -- Recursive Conquer
    [S11]    [S12]     [S21]    [S22]
      \      /           \      /           -- Combine
    [ Sol-1 ]          [ Sol-2 ]
             \            /
          [ Final Solution ]
```

1. **분할**: 문제를 $a$개의 $n/b$ 크기 문제로 쪼개는 비용이 발생함
2. **정복**: 쪼개진 문제들이 기저 조건에 도달할 때까지 재귀적으로 파고듦
3. **결합**: 각 단계에서 올라오는 부분 해들을 합치는 비용 $f(n)$이 전체 성능의 핵심이 됨

## 4. 문제점 및 개선방안

1. **과도한 재귀 호출로 인한 오버헤드**: 함수 호출 스택이 쌓여 메모리를 소모하고, 아주 작은 크기의 문제까지 재귀를 쓰면 호출 비용이 실제 연산 비용보다 커짐
   - **개선방안**: 문제가 일정 크기(Threshold) 이하로 작아지면 삽입 정렬 등 단순한 반복문 기반 알고리즘으로 전환하는 하이브리드 전략을 사용함 (확인: 호출 스택 깊이 및 전환 임계점)

2. **분할의 불균형 (Skewed Divide)**: 퀵 정렬처럼 피벗 선택에 따라 한쪽으로 치우쳐 분할될 경우, 탐색 깊이가 $\log n$이 아닌 $n$이 되어 $O(n^2)$으로 성능이 퇴화함
   - **개선방안**: 무작위 피벗 선정이나 중앙값(Median) 기반 분할을 통해 균형 잡힌 분할을 강제함 (확인: 최악의 경우 수행 시간)

3. **결합(Combine) 단계의 병목**: 하위 문제는 빠르게 풀었으나 이를 합치는 과정 $f(n)$이 비효율적이면 전체 성능이 저하됨
   - **개선방안**: 합치기 연산 자체를 최적화하거나(예: In-place Merge), 합치는 과정이 필요 없는 구조로 문제를 재설계함 (확인: 단계별 결합 소요 시간)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 대용량 정렬 | 데이터를 조각내어 각 코어에서 정렬(Conquer) 후 최종 병합(Combine) 수행 (Merge Sort) | 정렬 소요 시간, CPU 활용률 |
| 수치 해석 (Matrix) | Strassen 알고리즘을 통해 행렬 곱을 작은 행렬들의 연산으로 분할하여 연산 횟수 단축 | 부동소수점 연산량 (FLOPS) |
| 고속 푸리에 변환 (FFT) | 신호 데이터를 시간 영역에서 주파수 영역으로 분할 정복을 통해 $O(n \log n)$에 변환 | 신호 처리 지연 시간, 변환 정밀도 |
| 분산 처리 (MapReduce) | Map(Divide/Conquer) 단계에서 데이터를 분산 처리하고 Reduce(Combine) 단계에서 집계 | 데이터 셔플량, 전체 작업 완료 시간 |

> 요약: 병렬 처리가 가능한 독립적 구조를 설계할 때 가장 먼저 검토되는 알고리즘 모델임.

## 6. 결론

분할 정복은 복잡성을 '규모의 축소'를 통해 정복하는 알고리즘 설계의 정석임. 기술사는 분할 정복이 단순히 재귀를 쓰는 기법이 아니라, 하드웨어의 병렬성을 극대화하고 캐시 효율성(Cache-oblivious algorithms)을 높이는 전략적 도구임을 인식해야 함.

특히 멀티코어 및 분산 환경에서는 문제를 어떻게 독립적으로 쪼개어 부하를 분산할 것인지, 그리고 흩어진 결과를 어떻게 최소 비용으로 수집할 것인지가 설계의 핵심임. 결국 분할 정복은 '작게 나누면 관리가 쉽다'는 관리 철학을 수학적으로 구현한 것이며, 대규모 시스템의 성능 병목을 해결하는 가장 강력한 무기임.
