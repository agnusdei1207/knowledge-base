## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 문제를 동일 구조의 독립 부분 문제로 분할(Divide)하고, 각각 해결(Conquer)한 뒤, 결과를 결합(Combine)하는 알고리즘 설계 패러다임임 |
| **배경/필요성** | 대규모 문제를 직접 풀면 O(n²) 이상이 소요되며, 분할로 O(n log n) 이하로 시간을 줄여야 함 |
| **출제 의도** | 분할 정복의 3단계와 마스터 정리를 활용한 복잡도 분석 능력을 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| Divide   | --> | Conquer  | --> | Combine  |
| (분할)   |     | (정복)   |     | (결합)   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| Divide | 원래 문제를 크기가 작은 동일 구조 부분 문제로 분할함 | 피자를 여러 조각으로 자름 |
| Conquer | 부분 문제가 충분히 작으면 직접 풀고, 아니면 재귀로 다시 분할함 | 각 조각을 먹음 |
| Combine | 부분 문제의 해를 결합하여 원래 문제의 해를 구성함 | 먹은 결과를 종합 |

> 요약: Divide(분할) → Conquer(정복) → Combine(결합)으로 복잡 문제를 효율적으로 해결함.

## Ⅲ. 절차
```
+------------+     +------------+
| 문제분할   | --> | 기저조건   |
| (n/2씩)   |     | 확인       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 해결합     | <-- | 재귀해결  |
| (Merge)    |     | (Conquer) |
+------------+     +------------+
```

1. 분할: 입력을 절반(또는 k개)씩 분할하여 부분 문제를 생성함
2. 기저 조건 확인: 부분 문제 크기가 1 이하이면 직접 해를 반환함
3. 재귀 해결: 각 부분 문제를 동일 알고리즘으로 재귀적으로 해결함
4. 결합: 부분 해를 병합(Merge)하여 원래 문제의 해를 완성함

> 요약: 분할 → 기저 확인 → 재귀 → 결합의 4단계로 O(n log n)을 달성함.

## Ⅳ. 문제점
- 재귀 오버헤드: 함수 호출 스택이 깊어져 오버플로우 및 호출 비용이 발생함
- 부분 문제 불균등 분할: 퀵소트에서 피벗이 극단값이면 O(n²)으로 퇴화함
- Combine 비용: 병합 단계의 비용이 큰 경우(예: 행렬 곱) 전체 성능에 병목이 됨

## Ⅴ. 개선방안
- (단기) 소규모 전환: 부분 문제 크기가 임계치 이하이면 삽입 정렬 등 단순 알고리즘으로 전환함
- (중기) 균등 분할 보장: 중앙값 피벗 선택(Median-of-3)으로 불균등 분할을 방지함
- (장기) 병렬 분할 정복: Fork-Join 프레임워크로 부분 문제를 멀티코어에서 병렬 처리함

## Ⅵ. 전망
- 병합 정렬·FFT·Strassen 행렬 곱 등에서 분할 정복이 핵심 패러다임이며, MapReduce·Spark의 분산 처리 모델이 분할 정복 원리에 기반하여 확산될 전망임
