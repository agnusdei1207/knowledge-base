# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 분할 정복은 **알고리즘 설계 패러다임**의 하나로, 큰 문제를 **같은 형태의 독립적인 작은 문제로 쪼개(Divide)** 각각 재귀로 풀고(Conquer), 그 부분해를 **합쳐(Combine)** 전체 답을 만드는 기법이다.
- **왜 필요한가**: 크기 N 문제를 한 번에 O(N²)로 푸는 대신, 절반씩 쪼개면 각 단계가 O(N)이고 깊이가 log N이라 O(N log N)급으로 낮아지기 때문이다.
- **핵심 직관**: "**나눠서 각자 풀고 합친다**" — 부분 문제끼리 서로 겹치지 않아 저장할 필요가 없고, 쪼갤수록 문제가 자명해질 때까지 재귀로 파고든다.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안용 Ⅰ~Ⅵ·표에 나오는 분할 정복 고유 표기를 비유와 함께 먼저 세운다(O(N log N)의 성능 의미는 001·002, 병합·퀵 정렬 상세는 003 참조). 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 분할 정복 (상위 키워드) | 독립 부분 문제로 쪼개 풀고 합치는 설계 패러다임 | 큰 빨래를 나눠 각자 개고 합침 |
| 분할 (Divide) | 문제를 같은 형태의 더 작은 부분으로 나눔 | 배열을 절반으로 가름 |
| 정복 (Conquer) | 각 부분 문제를 재귀로 풂(작으면 직접) | 나뉜 절반을 각각 정렬 |
| 결합 (Combine) | 부분해를 합쳐 원 문제 답을 만듦 | 정렬된 두 절반을 병합 |
| 기저 사례 (Base Case) | 더 쪼갤 필요 없는 최소 크기(재귀 종료점) | 원소 1개면 이미 정렬됨 |
| 독립 부분 문제 | 부분끼리 겹치지 않아 저장 불필요 | 왼쪽 정렬이 오른쪽에 영향 없음 |
| 재귀 (Recursion) | 함수가 자신을 호출해 작은 문제로 위임 | 거울 속 거울처럼 같은 절차 반복 |
| 마스터 정리 (Master Theorem) | T(N)=aT(N/b)+f(N) 형태 복잡도 공식(075 참조) | 분할 재귀식의 시간 자동 계산기 |

## 깊이 이해
- **배경·문제의식**: 큰 입력을 한 덩어리로 처리하면 비교·연산이 N²로 늘 때가 많다. 문제가 **자기 유사(작은 자신으로 쪼개짐)**하면, 절반씩 나눠 부분해를 합치는 편이 전체를 훨씬 줄인다. 정렬·탐색·행렬 곱 등 광범위한 문제가 이 구조를 가진다.
- **작동 원리 (어떻게+왜)**:
  - **3단계**: ① Divide — 문제를 크기 N/b의 부분 a개로 나눔, ② Conquer — 각 부분을 재귀로 풀되 기저 사례면 직접 해결, ③ Combine — 부분해를 O(f(N))에 합침. 이 재귀식 T(N)=aT(N/b)+f(N)의 시간은 **마스터 정리**(075 참조)로 구한다.
  - **왜 빨라지나**: 병합 정렬은 매 단계 합치기가 O(N)이고 절반씩 나눠 깊이가 log N이므로 O(N log N)이다. 부분 문제가 **독립**이라 DP처럼 저장할 필요가 없다는 것이 핵심 차이다.
  - **병렬화 이점**: 부분 문제가 독립적이라 서로 다른 코어/노드에 나눠 동시에 풀 수 있어 병렬·분산(079 PRAM 참조)에 자연스럽다.
- **비유**: 큰 빨래 더미를 식구끼리 나눠 각자 개고, 다 갠 것을 합쳐 서랍에 넣는다. 각자의 빨래는 서로 겹치지 않으므로 누가 뭘 갰는지 장부에 적어 둘 필요가 없다(=저장 불필요).
- **구체 예시(수치·사례)**: 병합 정렬·퀵 정렬은 배열을 반씩 갈라 O(N log N)에 정렬한다(003 참조). 이진 탐색은 매번 후보를 절반으로 줄여 O(log N)(004 참조). 카라추바 곱셈은 N자리 곱을 3개 부분곱으로 나눠 O(N^1.585), 슈트라센 행렬 곱은 O(N^2.807)로 표준 O(N³)를 앞선다.
- **흔한 오해·주의점**:
  - **분할 정복과 DP를 혼동** — 둘 다 쪼개지만, 부분 문제가 **겹치면 DP(013)**, 겹치지 않으면 분할 정복이다. 피보나치를 분할 정복처럼 짜면 O(2^N)로 폭증한다.
  - **재귀 오버헤드 무시** — 입력이 아주 작으면 재귀 호출·스택 비용이 반복문보다 커, 실무 정렬은 작은 구간에서 삽입 정렬로 전환한다(하이브리드).
  - **합치기가 비싸면 이득이 준다** — Combine이 O(N²)이면 분할해도 느리다. f(N)이 작아야 전체가 빨라진다.

## 연결 개념
- **동적 프로그래밍 (013)**: 문제를 쪼개는 점은 같으나 부분 문제 중복 여부가 갈리는 대비 개념(겹치면 DP, 독립이면 분할 정복).
- **재귀·마스터 정리 (075)**: 분할 정복의 시간 T(N)=aT(N/b)+f(N)을 계산하는 정본 도구.
- **정렬 알고리즘 (003)**: 병합·퀵 정렬이 분할 정복의 대표 응용으로, 상세 동작은 003에서 다룸.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 분할 정복은 큰 문제를 독립적인 작은 문제로 나눠 재귀로 풀고 합치는 설계 패러다임임.
> 2. **가치**: 정렬·탐색·행렬 곱 등 자기 유사 문제를 O(N log N)급으로 낮추고 병렬화가 용이함.
> 3. **판단 포인트**: 부분 문제가 독립일 때 유효하며, 겹치면 DP(013)로 전환해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3단계 구조 이해 | Divide·Conquer·Combine과 기저 사례 | Combine 단계 언급 누락 |
| 복잡도 분석 | T(N)=aT(N/b)+f(N)·마스터 정리 | 재귀식·복잡도 근거 누락 |
| DP와의 차이 | 부분 문제 독립 여부가 갈림 | 분할 정복을 DP와 동일 단정 |

> 요약: 3단계(분할·정복·결합)와 재귀식·마스터 정리, 부분 문제 독립성으로 DP와 갈리는 점을 짚어야 함.

## Ⅰ. 개요 및 필요성
- 개요: 문제를 독립적인 작은 부분으로 나눠 재귀로 풀고 합치는 설계 패러다임임
- 배경: 큰 입력을 한 덩어리로 처리하면 O(N²)로 늘어나 규모 확장에 불리함
- 필요성: 자기 유사 구조의 정렬·탐색·수치 연산을 O(N log N)급으로 낮추고 병렬 처리할 필요가 있음

## Ⅱ. 구조 및 구성요소
선형 구조도 (분할·정복·결합 재귀):

    원 문제(크기 N) -> 분할(크기 N/b 부분 a개) -> 각 부분 재귀 정복 -> 부분해 결합 -> 전체 답
      / 기저 사례 도달 : 최소 크기면 재귀 없이 직접 해결
      / 결합 비용 f(N) : 부분해를 합치는 단계가 전체 복잡도를 좌우

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 분할(Divide) | 문제를 같은 형태 부분으로 나눔 | 나누는 개수 a·비율 b가 복잡도 결정 |
| 정복(Conquer) | 부분 문제를 재귀로 해결 | 기저 사례에서 재귀 종료 |
| 결합(Combine) | 부분해를 합쳐 원 답 생성 | f(N)이 크면 이득 감소 |
| 기저 사례 | 재귀 종료 조건(최소 크기) | 없으면 무한 재귀 |

> 요약: 분할·정복·결합 3단계로 재귀하며, 결합 비용 f(N)과 분할 계수 a·b가 전체 복잡도를 좌우함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (병합 정렬 기준):

    입력 배열 -> 절반으로 분할 -> 각 절반 재귀 정렬 -> 정렬된 두 절반 병합 -> 정렬 완료

1. 분할: 알고리즘이 배열을 크기 N/2 두 부분으로 나눔(퀵은 피벗 기준 분할)
2. 종료 판정: 부분 크기가 1이면 기저 사례로 이미 정렬된 것으로 간주함
3. 정복: 알고리즘이 각 부분을 재귀 호출해 독립적으로 정렬함
4. 결합: 정렬된 두 부분을 O(N)에 병합하며, 전체 시간은 마스터 정리로 O(N log N)임

> 요약: 배열을 반씩 나눠 각각 재귀 정렬한 뒤 O(N)에 병합하며, 깊이 log N과 곱해 O(N log N)이 됨.

## Ⅳ. 특징
- 지수 대비 단축: 자기 유사 문제를 절반씩 나눠 O(N²)를 O(N log N)급으로 낮춤
- 부분 문제 독립: 부분끼리 겹치지 않아 DP와 달리 답 저장이 불필요함
- 병렬화 용이: 독립 부분을 서로 다른 코어·노드에 분산해 동시 처리 가능함(079 참조)
- 결합 비용 의존: Combine이 O(f(N))으로 비싸면 분할 이득이 상쇄됨
- 재귀 오버헤드: 소입력에서 호출·스택 비용이 커, 실무는 작은 구간을 반복(삽입 정렬)으로 전환함

## Ⅴ. 심화 비교 및 적용 판단

동일 문제를 나눠 재귀로 푸는 분할 정복과 순차 처리하는 반복(iteration) 방식을 오버헤드·직관성·복잡도 축에서 대조함(DP와의 부분 문제 중복 차이는 013 참조).

| 구분 | 분할 정복(재귀) | 반복(iteration) |
|:---|:---|:---|
| 처리 방식 | 문제를 나눠 재귀 위임 | 루프로 순차 처리 |
| 추가 비용 | 호출 스택 O(log N)~O(N) | 스택 비용 거의 없음 |
| 적합 구조 | 자기 유사·병렬 가능 문제 | 선형 누적·단순 순회 |
| 대표 예 | 병합·퀵 정렬(003), 이진 탐색(004) | 합계·최댓값 스캔 |

> 요약: 자기 유사·병렬 문제는 분할 정복 재귀가 명료하고, 단순 선형 누적은 스택 비용 없는 반복이 유리함.

**리스크·대응:**
- 무한 재귀 — 기저 사례 누락으로 스택 오버플로 → 종료 조건 명시·최소 크기 검증
- 재귀 오버헤드 — 소입력에서 호출 비용 과다 → 임계 크기 이하 반복(삽입 정렬)으로 전환(하이브리드)
- 비싼 결합 — Combine이 O(N²)면 분할 이득 상쇄 → f(N)이 작은 분할 설계·마스터 정리로 사전 검증

**점검 지표:**
- 정확성 — 결합 결과 = 순차 처리 결과 — 소입력 대조로 확인
- 효율 — 재귀 깊이 ≈ log_b N — 호출 트레이스로 분할 비율 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 대용량 정렬·검색(하이브리드 정렬): TimSort·IntroSort로 병합·퀵 분할에 소구간 삽입 정렬을 결합해 O(N log N)과 실측 속도를 동시에 확보(003 참조)
2. 분산 데이터 처리(MapReduce): 데이터를 독립 청크로 분할(Map)해 노드별 병렬 처리 후 결합(Reduce)하는 대규모 배치 연산 설계
3. 수치·신호 연산(FFT·행렬 곱): 고속 푸리에 변환·슈트라센 곱으로 O(N log N)·O(N^2.807)에 대규모 변환·행렬 연산 가속

**결론:**
- 기술사 판단: 부분 문제가 독립이고 자기 유사·병렬 가능하면 분할 정복, 부분 문제가 겹치면 DP(013), 단순 선형 누적이면 반복을 택하는 조건부 선택이 유효함
- 향후 방향: 멀티코어·분산 환경 확산으로 독립 분할 구조를 살린 병렬 분할 정복(MapReduce·GPU 커널)이 대규모 처리의 기본 골격으로 자리잡고 있음
