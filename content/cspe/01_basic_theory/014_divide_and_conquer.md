## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 분할 정복(Divide and Conquer)은 원래 문제를 **동일한 구조의 더 작은 부분 문제로 분할(Divide)**하고, 각 부분 문제를 **재귀적으로 정복(Conquer)**한 뒤, 부분 해를 **결합(Combine)**하여 전체 해를 도출하는 알고리즘 설계 패러다임이다. DP와 달리 부분 문제가 **서로 독립적(Non-overlapping)**이라 중복 저장이 필요 없다.
> 2. **가치**: 병합 정렬(O(N log N)), 이진 탐색(O(log N)), Strassen 행렬 곱셈(O(N^2.81)), 최근접 점 쌍(O(N log N)) 등 정렬·탐색·수치 계산의 핵심 알고리즘이 분할 정복으로 설계되며, 재귀 관계식을 Master Theorem으로 체계적으로 분석할 수 있다.
> 3. **융합**: MapReduce는 분할 정복을 분산 환경에 확장한 것이며, 병렬 처리·FFT(고속 푸리에 변환)·컴파일러 파싱(CYK)·컴퓨터 그래픽스(BSP Tree) 등 병렬화·재귀 분해가 필요한 모든 영역의 설계 원형이다.

## Ⅰ. 개요 및 필요성

- **개념**: 분할 정복은 문제를 **같은 유형의 독립적 부분 문제**로 쪼개어 재귀적으로 해결하고, 부분 해를 합쳐 전체 해를 구성하는 세 단계(Divide → Conquer → Combine) 패러다임임
- **필요성**: N개 원소 정렬을 단순 비교하면 O(N²)이지만, 분할 정복(병합 정렬)은 O(N log N)으로 줄임. N=10⁶일 때 10¹²번 → 약 2×10⁷번으로 약 50,000배 차이가 나며, 이는 "실시간 처리 가능 여부"의 경계를 결정함
- **비유**: 1,000페이지 사전에서 단어를 찾을 때, 첫 페이지부터 순서대로 보면 평균 500페이지를 넘겨야 하지만(O(N)), 가운데를 펼쳐서 앞뒤 절반 중 하나를 버리면 10번 만에 찾음(O(log N)). 이 "절반 버리기"가 분할 정복의 본질임
- **등장 배경 및 발전 과정**:
  1. **1945년**: 폰 노이만(John von Neumann)이 병합 정렬을 제안하며 분할 정복 아이디어를 최초로 형식화함
  2. **1960년대**: Karatsuba 곱셈(O(N^1.585))이 등장하여 O(N²) 곱셈의 벽을 깸. Cooley-Tukey FFT(O(N log N))가 신호 처리를 혁신함
  3. **1969년**: Strassen이 행렬 곱셈을 O(N^2.81)로 단축함. 이후 분할 정복의 재귀 분석을 위한 Master Theorem이 체계화됨(CLRS, 1990)
  4. **2004년**: Google MapReduce 논문이 분할 정복을 수천 대의 서버로 확장하는 분산 프레임워크를 발표함

```text
+-----------------------------------------------------------------------+
|         분할 정복의 3단계 — Divide → Conquer → Combine               |
+-----------------------------------------------------------------------+
|                                                                       |
|  [원래 문제: 크기 N]                                                  |
|         |                                                             |
|    1) Divide — 문제를 a개의 부분 문제(크기 N/b)로 분할               |
|         |                                                             |
|    +----+----+----+                                                   |
|    |    |    |    |                                                    |
|    v    v    v    v                                                    |
|  [N/b] [N/b] ... [N/b]   (a개의 독립적 부분 문제)                    |
|    |    |    |    |                                                    |
|    2) Conquer — 각 부분 문제를 재귀적으로 해결                       |
|    |    |    |    |       (크기가 충분히 작으면 직접 해결)             |
|    v    v    v    v                                                    |
|  [해1] [해2] ... [해a]                                                |
|    |    |    |    |                                                    |
|    +----+----+----+                                                   |
|         |                                                             |
|    3) Combine — 부분 해를 결합하여 전체 해 도출                      |
|         |                                                             |
|         v                                                             |
|  [전체 해: 크기 N의 문제에 대한 답]                                   |
|                                                                       |
|  시간 복잡도 재귀식: T(N) = a·T(N/b) + f(N)                         |
|  - a: 부분 문제 개수                                                 |
|  - b: 분할 비율 (각 부분 문제 크기 = N/b)                            |
|  - f(N): Divide + Combine 비용                                       |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** 분할 정복은 크기 N인 문제를 a개의 크기 N/b인 부분 문제로 나누고(Divide), 각 부분 문제를 재귀적으로 풀고(Conquer), 부분 해를 합쳐 전체 해를 만든다(Combine). 핵심은 **부분 문제가 서로 독립적**이라는 점이다. 병합 정렬에서 왼쪽 반과 오른쪽 반은 서로의 결과에 의존하지 않으므로, 각각을 독립적으로 정렬한 뒤 병합만 하면 된다. 이 독립성 덕분에 DP의 메모이제이션 없이 순수 재귀로 작동한다. 재귀의 전체 비용은 T(N) = a·T(N/b) + f(N)이라는 점화식으로 표현되며, 이 식을 Master Theorem으로 분석하여 시간 복잡도를 결정한다.

- **📢 섹션 요약 비유**: 분할 정복은 "1,000장의 시험지를 혼자 채점하지 말고, 조교 4명에게 250장씩 나눠주고, 각자 채점한 결과를 합치는 것"과 같습니다. 핵심은 250장짜리 채점이 서로 독립적이라는 것입니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 내부 동작 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **Divide(분할)** | 문제를 더 작은 부분 문제로 쪼갬 | 배열을 반으로 나누기, 탐색 범위 절반 축소 | 피벗 선택(퀵 정렬), 중간점(이진 탐색) | 사전을 반으로 펼침 |
| **Conquer(정복)** | 부분 문제를 재귀적으로 해결 | 기저 조건(크기 1 이하)이면 직접 해결, 아니면 재귀 호출 | 재귀 호출 스택 | 각 조교가 맡은 분량 채점 |
| **Combine(결합)** | 부분 해를 합쳐 전체 해 생성 | 병합(merge), 접합, 최솟값 선택 | 병합 정렬의 merge, 최근접 쌍의 strip 검사 | 채점 결과를 통합 |
| **Base Case(기저 조건)** | 재귀 종료 | 크기 0 또는 1인 부분 문제는 답이 자명함 | — | 시험지 1장은 바로 채점 |
| **Master Theorem** | 재귀 복잡도 분석 도구 | T(N) = aT(N/b) + f(N)의 세 경우 판정 | CLRS Ch.4 | 인건비 계산 공식 |

> 요약: Divide(분할)로 문제를 쪼개고, Conquer(정복)로 재귀 해결하며, Combine(결합)으로 합친다. 복잡도는 Master Theorem으로 판정함.

### Master Theorem 판정 흐름

T(N) = a·T(N/b) + f(N)에서 **분할이 만드는 재귀 작업량**(N^(log_b(a)))과 **Divide+Combine 비용**(f(N))의 크기 비교로 전체 복잡도가 결정된다.

```text
+-----------------------------------------------------------------------+
|              Master Theorem — 3가지 경우 판정 흐름                    |
+-----------------------------------------------------------------------+
|                                                                       |
|  주어진 재귀식: T(N) = a·T(N/b) + f(N)                               |
|  핵심 지수: c_crit = log_b(a)  (재귀 트리 잎 노드의 총 작업량 지수)  |
|                                                                       |
|  f(N)과 N^c_crit를 비교한다:                                         |
|         |                                                             |
|    +----+----+-----------+                                            |
|    |         |           |                                             |
|    v         v           v                                             |
|  Case 1   Case 2     Case 3                                          |
|                                                                       |
|  f(N) = O(N^c)      f(N) = Θ(N^c_crit   f(N) = Ω(N^c)              |
|  c < c_crit          · log^k(N))         c > c_crit                  |
|  (잎이 지배)         (균형)               (루트가 지배)               |
|    |                   |                    |                         |
|    v                   v                    v                         |
|  T(N) = Θ(N^c_crit) T(N) = Θ(N^c_crit   T(N) = Θ(f(N))            |
|                        · log^(k+1)(N))                                |
|                                                                       |
|  예시:                                                                |
|  Case 1: Strassen   Case 2: 병합 정렬   Case 3: —                   |
|  a=7, b=2            a=2, b=2, f=Θ(N)   (정규조건 필요,             |
|  c_crit=log2(7)≈2.81  c_crit=1=c          드묾)                     |
|  f(N)=Θ(N^2)          T=Θ(N log N)                                  |
|  2 < 2.81                                                            |
|  T=Θ(N^2.81)                                                        |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** Master Theorem은 재귀 트리를 레벨별로 분석한다. c_crit = log_b(a)는 재귀 트리의 **잎 노드 총 작업량**의 다항 지수이다. **Case 1**: f(N)이 잎보다 느리게 증가하면(c < c_crit), 전체 비용은 잎이 지배하여 T(N) = Θ(N^c_crit)이다. Strassen 곱셈은 a=7, b=2이므로 c_crit = log₂7 ≈ 2.81이고, Divide+Combine 비용 f(N) = Θ(N²)가 N^2.81보다 느리게 증가하므로 T(N) = Θ(N^2.81)이다. **Case 2**: f(N)과 잎의 증가율이 같으면(f(N) = Θ(N^c_crit · log^k N)), 각 레벨의 비용이 균형을 이루어 T(N) = Θ(N^c_crit · log^(k+1) N)이다. 병합 정렬은 a=2, b=2, f(N)=Θ(N)이므로 c_crit=1, k=0이고, T(N) = Θ(N log N)이다. **Case 3**: f(N)이 잎보다 빠르게 증가하면, 루트 레벨의 Divide+Combine 비용이 지배하여 T(N) = Θ(f(N))이다(정규 조건 af(N/b) ≤ cf(N) 충족 필요).

- **📢 섹션 요약 비유**: Master Theorem은 "회사의 총 인건비를 구하는 공식"과 같습니다. 일을 나누는 관리자(Divide+Combine)와 실제 일하는 말단 직원(잎 노드) 중 누가 더 비싸냐에 따라, 총 비용이 관리비·인건비·둘의 합으로 결정됩니다.

## Ⅲ. 비교 및 연결

### 비교 1: 분할 정복 vs DP

DP와의 핵심 차이는 013_dynamic_programming.md에서 비교표로 다루었으므로, 여기서는 **분할 정복 관점**에서의 판단 기준에 집중한다.

| 판단 기준 | 분할 정복 | DP |
|:---|:---|:---|
| **부분 문제 독립성** | 독립적 — 메모이제이션 불필요 | 중복(Overlapping) — 저장 필수 |
| **해법 방향** | 트리 구조 재귀(top-down only) | Top-down 또는 Bottom-up |
| **병렬화 가능성** | 자연스러움 — 독립 부분을 동시 처리 | 의존성 때문에 병렬화 제한 |
| **복잡도 분석 도구** | Master Theorem (닫힌 형태) | 상태 수 × 전이 비용 직접 계산 |
| **선택 기준** | 부분 문제가 겹치지 않으면 분할 정복 | 부분 문제가 겹치면 DP |

> 요약: 부분 문제가 독립적이면 분할 정복, 겹치면 DP. 이 판단이 알고리즘 설계의 첫 번째 분기점임.

### 비교 2: 분할 정복 vs 탐욕

| 판단 기준 | 분할 정복 | 탐욕(Greedy) |
|:---|:---|:---|
| **최적해 보장** | 재귀적 완전 탐색 — 보장됨 | 지역 최적 선택 — 특정 조건에서만 보장 |
| **부분 문제 처리** | 모든 부분 문제를 해결 후 결합 | 한 번의 선택 후 나머지만 해결 |
| **대표 알고리즘** | 병합 정렬, Strassen | 다익스트라, 크루스칼, 허프만 |
| **설계 복잡도** | 분할+결합 로직 설계 필요 | 탐욕 선택 속성 증명 필요 |

> 요약: 분할 정복은 "나눠서 다 풀고 합치기", 탐욕은 "지금 가장 좋은 것만 선택". 탐욕은 빠르지만 최적 보장 조건이 까다로움.

### 대표 알고리즘별 분할 정복 적용

| 알고리즘 | a | b | f(N) | T(N) | Master Case |
|:---|:---|:---|:---|:---|:---|
| 이진 탐색 | 1 | 2 | Θ(1) | Θ(log N) | Case 2 |
| 병합 정렬 | 2 | 2 | Θ(N) | Θ(N log N) | Case 2 |
| 퀵 정렬(평균) | 2 | 2 | Θ(N) | Θ(N log N) | Case 2 |
| Strassen 곱셈 | 7 | 2 | Θ(N²) | Θ(N^2.81) | Case 1 |
| Karatsuba 곱셈 | 3 | 2 | Θ(N) | Θ(N^1.585) | Case 1 |
| 최근접 점 쌍 | 2 | 2 | Θ(N) | Θ(N log N) | Case 2 |

> 요약: 대부분의 분할 정복 알고리즘은 Master Theorem Case 1 또는 Case 2에 해당하며, 나이브 방법 대비 다항 지수를 줄이는 데 기여함.

### 과목 융합 관점
- **네트워크**: MapReduce는 분할 정복을 분산 클러스터로 확장한 것임. Mapper가 Divide+Conquer, Reducer가 Combine 역할을 담당함
- **하드웨어**: 병렬 프로세서(GPU, 멀티코어)에서 독립적 부분 문제를 동시에 처리하는 fork-join 모델은 분할 정복의 하드웨어 구현임
- **소프트웨어 공학**: 컴파일러의 구문 분석(파싱)은 문법 규칙을 재귀적으로 분할하여 파스 트리를 구성하는 분할 정복임

- **📢 섹션 요약 비유**: DP가 "같은 문제를 메모해서 다시 안 푸는 것"이라면, 분할 정복은 "애초에 같은 문제가 안 나오게 깔끔하게 나누는 것"입니다. 나눈 조각이 겹치면 DP, 겹치지 않으면 분할 정복을 씁니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — MapReduce로 대규모 로그 분석**: 하루 10TB의 웹 서버 로그에서 URL별 접속 빈도를 집계하는 문제는, 단일 서버로는 메모리·시간 한계에 부딪힘. MapReduce는 로그를 N개 청크로 분할(Divide)하고, 각 Mapper가 독립적으로 URL별 카운트를 계산(Conquer)한 뒤, Reducer가 같은 URL의 카운트를 합산(Combine)함. 서버 1,000대에서 10TB를 1,000개 × 10GB 청크로 나누면, 단일 서버 10시간 작업이 약 10분으로 단축됨

2. **시나리오 — Strassen 행렬 곱셈으로 과학 계산 가속**: 기상 시뮬레이션에서 10,000×10,000 행렬의 반복 곱셈이 필요함. 나이브 O(N³)는 10¹² 연산이지만, Strassen O(N^2.81)은 약 4.2×10¹¹ 연산으로 약 2.4배 빠름. 실제로는 캐시 효율이 낮아 N > 64 이상에서만 이점이 있으며, 하이브리드(작은 행렬은 나이브, 큰 행렬은 Strassen)로 구현함

### 도입 체크리스트
- **기술적**: 부분 문제가 독립적인가? 겹치면 DP로 전환해야 함. Combine 비용이 분할 이점을 상쇄하지 않는가?
- **운영 및 보안적**: 재귀 깊이가 스택 오버플로우를 유발하지 않는가? (N=10⁶일 때 log₂N ≈ 20으로 안전, 불균형 분할 시 최악 O(N) 깊이로 위험)

### 안티패턴
- **부분 문제가 겹치는데 분할 정복 사용**: 피보나치를 분할 정복(순수 재귀)으로 풀면 O(2^N). 부분 문제가 겹치면 반드시 DP(메모이제이션)로 전환해야 함 (013 DP 참조)
- **불균형 분할 방치**: 퀵 정렬에서 피벗이 항상 최솟값이면 한쪽은 N-1, 다른 쪽은 0이 되어 O(N²)로 퇴화함. 삼중 중앙값(Median-of-three) 피벗 선택이나 랜덤 피벗으로 방지함
- **Combine 비용 과소평가**: Combine이 O(N²)이면 분할의 O(N log N) 이점이 사라짐. Combine 비용을 포함한 Master Theorem 분석이 선행되어야 함

- **📢 섹션 요약 비유**: 분할 정복은 "피자를 똑같이 나누는 것"이 핵심인데, 한 사람이 피자 90%를 가져가면(불균형 분할) 나누는 의미가 없어집니다. 그리고 남은 조각을 합칠 때 비용(Combine)이 나누는 이점보다 크면 차라리 안 나누는 게 낫습니다.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 분할 정복 미적용 (나이브) | 분할 정복 적용 | 개선 효과 |
|:---|:---|:---|:---|
| **정렬** | O(N²), N=10⁶ 시 10¹² 연산 | O(N log N), 약 2×10⁷ 연산 | 약 **50,000배** 빠름 |
| **탐색** | O(N), N=10⁶ 시 10⁶ 비교 | O(log N), 약 20 비교 | 약 **50,000배** 빠름 |
| **행렬 곱셈** | O(N³), N=10⁴ 시 10¹² 연산 | O(N^2.81), 약 4.2×10¹¹ 연산 | 약 **2.4배** 빠름 |
| **병렬화** | 순차 처리 (1노드) | 분할 → 독립 노드에 분배 | 노드 수에 비례한 선형 확장 |

> 요약: 분할 정복은 다항 지수를 줄이거나(Strassen), 전체 차수를 한 단계 낮추는(정렬, 탐색) 효과를 제공하며, 독립 부분 문제 구조 덕분에 자연스러운 병렬화가 가능함.

### 미래 전망
- **양자 분할 정복**: Grover 탐색(O(√N))은 양자 컴퓨터에서의 분할 정복 확장이며, 양자 병렬성을 활용한 재귀 분할 기법이 연구 중임
- **AI 학습 파이프라인**: 대규모 모델의 데이터 병렬 학습(Data Parallelism)은 학습 데이터를 GPU 수만큼 분할(Divide)하고, 각 GPU가 독립적으로 그래디언트를 계산(Conquer)한 뒤, 그래디언트를 평균화(Combine)하는 분할 정복 구조임

### 참고 표준
- **Cormen et al. (CLRS)**: Ch.2 병합 정렬, Ch.4 Master Theorem, Ch.33 최근접 점 쌍
- **Strassen, V. (1969)**: "Gaussian Elimination is not Optimal" — 행렬 곱셈 O(N^2.81)
- **Dean & Ghemawat (2004)**: "MapReduce: Simplified Data Processing on Large Clusters"

분할 정복은 "큰 문제를 작은 독립 조각으로 나누고, 각각 풀고, 합친다"는 직관적 원리지만, 이 원리가 O(N²)→O(N log N), O(N³)→O(N^2.81)의 극적 개선을 만든다. 적용의 핵심은 (1) 부분 문제가 독립적인지 확인(겹치면 DP), (2) 균형 잡힌 분할, (3) Combine 비용 통제이며, 이 세 가지를 충족하면 정렬·탐색·수치·분산 처리 전 영역에 걸쳐 적용 가능하다.

- **📢 섹션 요약 비유**: 분할 정복은 "혼자 하면 1년 걸리는 일을 12명이 한 달씩 나눠 하고 결과를 합치면 1달에 끝나는" 원리입니다. 단, 나눈 일이 서로 독립적이어야 하고, 결과를 합치는 비용이 싸야 합니다.
