## 미리 알고가기

- 기저 조건: 더 나누지 않고 바로 답을 내는 최소 문제 조건임
- 독립 부분 문제: 서로의 결과를 공유하지 않고 따로 풀 수 있는 하위 문제임
- 결합 비용: 하위 문제의 답을 원래 문제의 답으로 합치는 비용임
- 재귀식: 문제 크기에 따른 비용을 하위 문제 비용과 결합 비용으로 나타낸 식임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 큰 문제를 같은 형태의 작은 문제로 나누고, 각 하위 문제를 푼 뒤 결과를 합쳐 원래 문제의 답을 만드는 설계 기법임
- **배경/필요성**: 큰 문제를 한 번에 풀면 계산과 구현이 복잡해질 수 있음. 문제를 독립된 작은 단위로 나누면 처리 흐름이 단순해지고 병렬화도 쉬워짐

## Ⅱ. 특징

- 같은 형태의 하위 문제로 반복 분해하므로 재귀 구조와 잘 맞음
- 하위 문제가 독립적이면 동시에 계산할 수 있음
- 분할 이익보다 결합 비용이 크면 성능 개선이 줄어듦
- 하위 문제가 반복되면 저장이 필요한 동적 프로그래밍이 더 적합할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 | 동적 프로그래밍 | 백트래킹 |
|:---|:---|:---|:---|
| 하위 문제 관계 | 독립적 | 반복됨 | 선택 경로로 이어짐 |
| 처리 방식 | 나누고 푼 뒤 합침 | 저장하고 재사용함 | 조건을 어기면 되돌아감 |
| 강점 | 구조 단순, 병렬화 용이 | 중복 계산 감소 | 불필요한 경로 제거 |
| 대표 문제 | 병합 정렬, 퀵 정렬, FFT | 배낭, 편집 거리 | 스도쿠, 조합 탐색 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원문제 | 분할 전 전체 입력임 |
| 분할 기준 | 문제를 어떤 크기의 하위 문제로 나눌지 정하는 기준임 |
| 기저 조건 | 재귀를 멈추고 답을 반환하는 조건임 |
| 결합 함수 | 하위 문제의 답을 합쳐 원래 문제의 답을 만듦 |

```text
+--------+     +----------+     +----------+     +--------+
| 원문제 | --> | 하위 문제 | --> | 각각 해결 | --> | 결합 |
+--------+     +----------+     +----------+     +--------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 기저 확인 | --> | 문제 분할 | --> | 재귀 해결 | --> | 결과 결합 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 기저 조건이면 바로 답을 반환함
2. 아니면 같은 형태의 작은 문제로 나눔
3. 각 하위 문제를 독립적으로 해결함
4. 하위 결과를 합쳐 최종 답을 만듦

## Ⅵ. 실무 적용 및 유의점

1. 하위 문제가 서로 겹치면 같은 계산이 반복되므로 분할 정복 대신 동적 프로그래밍 전환을 검토해야 함
2. 재귀 깊이가 커지는 입력에서는 스택 사용량을 확인하고 필요하면 반복 구현이나 분할 크기 조정을 적용해야 함

## Ⅶ. 결론

- 분할 정복은 독립적인 하위 문제로 나눌 때 효과적이며, 결합 비용과 재귀 깊이를 함께 관리해야 함
