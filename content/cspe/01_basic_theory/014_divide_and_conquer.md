# 📖 【암기용】 개념 완전 이해

> 목적: 분할 정복을 독립 하위 문제와 병합 비용 관점으로 이해하게 만든다.

## 한눈에
- **개요**: 큰 문제를 같은 형태의 작은 문제로 나누고, 각각 해결한 뒤 결과를 합치는 알고리즘 설계 기법
- **왜 필요한가**: 전체를 한 번에 처리하기 어려운 문제를 균등 분할하면 재귀 구조와 병렬 처리 가능성이 생김
- **핵심 직관**: 큰 일을 여러 조각으로 나눠 따로 처리하고, 마지막에 조립함

## 깊이 이해
- **배경·문제의식**: 정렬, 탐색, 행렬 계산은 입력 크기가 커질수록 직접 처리 비용이 증가함. 분할 정복은 입력 크기를 절반 또는 일정 비율로 줄여 재귀적으로 해결함
- **작동 원리**: ① Divide로 문제를 쪼갬, ② Conquer로 하위 문제를 해결함, ③ Combine으로 결과를 병합함. 하위 문제가 겹치지 않는 점이 DP와 다름
- **비유**: 책 1,000쪽을 한 사람이 검토하는 대신 10명이 100쪽씩 나누어 검토하고, 마지막에 검토 결과를 합치는 방식임
- **구체 예시**: 병합 정렬은 배열을 절반씩 나누고 병합 단계에서 O(n)을 사용해 전체 O(n log n)을 달성함. 이진 탐색은 매 단계 탐색 범위를 1/2로 줄여 O(log n)임
- **흔한 오해·주의점**: 분할만 한다고 비용이 줄지 않음. 병합 비용이 크거나 하위 문제가 중복되면 DP 또는 다른 접근이 필요함

## 연결 개념
- 재귀 — 분할 정복 구현의 기본 구조
- 동적 프로그래밍 — 중복 하위 문제가 있으면 저장 재사용 검토
- 병렬 처리 — 독립 하위 문제는 멀티코어·분산 실행 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 분할 정복은 문제를 독립 하위 문제로 분할하고 결과를 병합해 원 문제를 해결하는 재귀적 설계 기법이다.
> 2. **가치**: 이진 탐색 O(log n), 병합 정렬 O(n log n)처럼 입력 크기 축소와 병합 비용으로 복잡도를 산정한다.
> 3. **판단 포인트**: 분할 균형, 종료 조건, 병합 비용, 하위 문제 중복 여부를 함께 검토해야 한다.

---

## Ⅰ. 개요 및 필요성

개요: 분할 정복은 문제를 나누고 합쳐 해결한다. 대규모 입력을 직접 처리하면 계산량이 증가하므로 입력 크기를 단계적으로 줄이는 전략이 필요하다. 하위 문제가 독립이면 재귀와 병렬 처리를 통해 계산 구조를 단순화할 수 있다.

---

## Ⅱ. 구조 및 구성요소

```text
Original Problem -> Divide -> Subproblem A/B -> Conquer -> Combine -> Result
                 / Divide: reduce size n/b
                 / Conquer: solve independent subproblems
                 / Combine: merge partial results
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Divide | 원 문제를 작은 문제로 분할 | 보통 n/2 또는 k개 분할 |
| Conquer | 하위 문제를 재귀 해결 | 종료 조건 필요 |
| Combine | 하위 결과를 병합 | 병합 정렬은 O(n), 이진 탐색은 O(1) |
| Recurrence | 복잡도 표현 | `T(n)=aT(n/b)+f(n)` |

> 요약: 분할 정복은 분할 수, 축소 비율, 병합 비용을 점화식으로 표현해 복잡도를 계산한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 입력 -> 종료 조건 확인 -> 하위 문제 분할 -> 재귀 해결 -> 결과 병합 -> 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 크기와 종료 조건 확인 | n=1, low>high 등 |
| 2 | 문제를 하위 문제로 분할 | 균형 분할 여부 |
| 3 | 하위 문제를 독립 해결 | 중복 호출 없음 |
| 4 | 부분 결과를 병합·반환 | 병합 비용 f(n) 산정 |

> 요약: 분할 정복은 종료 조건을 기준으로 재귀를 멈추고, 병합 단계의 비용까지 포함해 전체 복잡도를 판단한다.

---

## Ⅳ. 특징

| 구분 | 분할 정복 | 동적 프로그래밍 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 하위 문제 | 독립적 | 중복 가능 | 중복 상태 수 |
| 저장 방식 | 결과 저장 필수 아님 | DP 테이블·메모 사용 | 공간 O(1)~O(nm) |
| 대표 알고리즘 | 병합 정렬, 퀵 정렬, 이진 탐색 | 배낭, LCS, 편집 거리 | 문제 구조 |
| 복잡도 산정 | `aT(n/b)+f(n)` | 상태 수 x 전이 수 | Master theorem vs 점화식 |

> 요약: 분할 정복은 독립 하위 문제와 병합 비용이 핵심이며, 중복 하위 문제가 보이면 DP로 전환한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단순 반복/완전처리 | 분할 정복 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 전체 입력 한 번에 처리 | 독립 하위 문제와 병합 | 하위 문제가 중복되지 않을 때 |
| 비용/성능 | 문제별 직접 산정 | `T(n)=aT(n/b)+f(n)` | Master theorem 적용 가능 |
| 운영/위험 | 구현 단순 | 분할 불균형·combine 병목 | 병렬화 시 병합 비용 측정 |

> 요약: 분할 정복은 독립 하위 문제와 제한된 병합 비용이 있을 때 점화식 기반으로 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 분할 불균형 | pivot·partition 편향 | randomized pivot, sampling | subproblem size ratio |
| 병합 병목 | combine 비용 f(n) 과대 | k-way merge, streaming combine | combine time ratio |
| 재귀 비용 | 과도한 call depth | iterative 전환, threshold 설정 | recursion depth |

> 요약: 분할 정복 리스크는 분할 균형, 병합 비율, 재귀 깊이이며 각 지표를 계측한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 점화식 | a, b, f(n) 명시 | 설계 리뷰 |
| 병렬성 | 독립 하위 문제 비율 산정 | 프로파일링 |
| 정확도 | 병합 결과 불변식 통과 | 단위·속성 테스트 |

> 요약: 성공 기준은 점화식 명확성, 독립 실행 가능성, 병합 결과 검증이다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 정렬 처리: 병합 정렬로 O(n log n) 상한을 확보하고, 외부 정렬에서는 청크 분할 후 k-way merge 적용
2. 검색 처리: 정렬 배열에서 이진 탐색으로 비교 횟수를 n에서 log2(n) 수준으로 축소
3. 병렬 계산: 독립 하위 문제를 thread pool 또는 MapReduce로 분배하고, combine 단계의 네트워크 shuffle 비용을 별도 산정

**결론 (2줄):**
- 기술사 판단: 하위 문제가 독립이고 병합 비용이 제한되면 분할 정복, 중복 상태가 많으면 DP, 지역 최적 선택이 증명되면 탐욕을 적용함
- 향후 방향: 멀티코어·분산 환경에서는 분할 균형과 combine 병목을 동시에 측정해 병렬 이득을 검증해야 함
