# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 거대하고 복잡한 문제를 해결하기 쉬운 작은 단위의 동일한 문제들로 쪼개어(분할), 각각을 푼(정복) 다음 다시 하나로 합치는(결합) 하향식 설계 패턴이다.
- **왜 필요한가**: 수천만 개의 데이터를 통째로 정렬하려면 시간이 기하급수적으로 늘지만, 반씩 쪼개어 풀면 규칙이 단순해지고 듀얼코어처럼 병렬 처리가 가능해지기 때문이다.
- **핵심 직관**: 문제를 계속 반토막 낸다. 더 쪼갤 수 없을 만큼 작아지면 문제를 풀고, 그 결과들을 위로 던져 올리면서 퍼즐 맞추듯 합친다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 분할 (Divide) | 큰 문제를 성격이 같은 여러 개의 작은 하위 문제로 쪼개는 단계 | 두꺼운 문제집을 앞 절반, 뒤 절반으로 찢어 나누기 |
| 정복 (Conquer) | 더 이상 나눌 수 없을 만큼 작아진 문제를 실제로 푸는 단계 | 1장짜리 종이에 쓰인 내용만 읽고 바로 답 쓰기 |
| 결합 (Combine) | 해결된 하위 문제의 정답들을 뭉쳐서 원래 문제의 정답으로 갱신하는 단계 | 푼 종이들을 순서대로 스테이플러로 찍어 제출하기 |

## 깊이 이해
- **배경·문제의식**: 처음부터 배열 전체를 무식하게 루프를 돌며 정렬하려 하면 O(N^2)의 비효율을 낳는다. 문제를 '서로 영향 주지 않는 독립된' 작은 덩어리로 잘라 복잡도를 O(N log N)으로 낮추려는 아이디어다.
- **작동 원리**: 재귀 호출(Recursion) 함수가 필수 엔진 역할을 한다.
  1. 전체 배열을 반으로 자른다. (Divide)
  2. 잘린 배열을 또 자르며 원소가 1개가 될 때까지 재귀 호출한다. 원소가 1개면 스스로 정렬된 상태이므로 문제가 풀린다(Conquer).
  3. 리턴되며 인접한 조각들을 정렬하면서 묶어준다. (Combine)
- **비유**: 100명 성적표 정렬 지시를 반장 2명에게 50장씩 넘기고, 분단장에게 25장씩 넘겨 결국 끝단의 조장들이 자기가 쥔 2장만 비교해 윗선으로 올리면 전체 정렬이 완료되는 관리 조직의 위임 체계다.
- **구체 예시**: 병합 정렬(Merge Sort)은 정확히 반으로 쪼개고 나중에 합칠 때 정렬한다. 퀵 정렬(Quick Sort)은 특정 기준값(피벗)으로 쪼갤 때 미리 정렬하고 합치는 과정은 없다. 이진 탐색은 반을 버리므로 결합 과정이 없다.
- **흔한 오해·주의점**: 동적 프로그래밍(DP)과 혼동된다. 분할 정복은 쪼개진 문제들이 서로 **전혀 겹치지 않는 독립적 상태**일 때(예: 배열 좌우 절반은 무관) 쓴다. DP는 쪼갠 문제가 중복되어 캐싱이 필요할 때 쓴다.

## 연결 개념
- 재귀 알고리즘 (분할 정복의 3단계를 코드로 옮기는 구현체)
- 마스터 정리 (분할 정복의 시간 복잡도를 수식으로 구하는 공식)
- (013 동적 프로그래밍 참조) 부분 문제의 독립성에 따른 차이

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 하향식 재귀 기법을 이용해 거대 문제를 동일한 성격의 독립된 부분 문제들로 나누어 해결하는 알고리즘 패턴.
> 2. **가치**: 대규모 정렬 및 연산 복잡도를 O(N log N)으로 낮추고, 각 부분 문제의 독립성 덕에 분산 병렬 컴퓨팅(MapReduce) 이식에 용이.
> 3. **판단 포인트**: 부분 문제가 서로 겹치지 않는(Non-Overlapping) 구조일 때 적용해야 중복 연산으로 인한 메모리 낭비를 막는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘의 3단계 설계 메커니즘 이해 | Divide, Conquer, Combine 3단계 흐름도 | 재귀 함수라는 개념만 서술하고 결합(Combine) 과정 누락 |
| 타 패러다임(DP)과의 구별 역량 | 부분 문제의 독립성(Non-Overlapping) 판별 | DP와의 명확한 비교 없이 단순 정렬 사례만 나열 |

> 요약: 분할·정복·결합의 3단계 라이프사이클을 구체화하고, DP와의 '독립적 계산 여부' 차이를 명확히 대조하는 것이 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: 해결하기 힘든 단일 문제를 더 이상 쪼갤 수 없는 동일 유형의 기저 문제로 반복 분할한 후 해답을 병합하는 최적화 기법
- 배경: 단순 순차 접근 기법으로는 100만 건 이상의 대규모 데이터 처리 시 O(N^2) 이상의 다항 시간 복잡도로 스루풋 한계 봉착
- 필요성: 멀티 코어 환경에서 독립적 연산의 스레드 분배(Fork-Join)를 통해 처리량(Throughput)을 기하급수적으로 극대화하는 아키텍처 필수

---

## Ⅱ. 구조 및 구성요소

```text
대규모 입력(N) -> [Divide: 조건 분할] -> [Conquer: 기저 풀이] -> [Combine: 결과 병합] -> 최종 최적해
                                          |                     |
                                          +-> 하향식 재귀 호출  +-> 상향식 정렬 병합
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 분할 (Divide) | 기존 문제를 크기가 더 작은 동일한 유형의 부분 문제들로 쪼갬 | 퀵 정렬은 피벗 기준 비대칭 분할, 병합 정렬은 무조건 절반 분할 |
| 정복 (Conquer) | 크기가 충분히 작아진(기저 조건) 부분 문제의 정답 확정 도출 | 원소가 1개일 때 자기 자신을 답으로 반환(재귀 탈출 조건) |
| 결합 (Combine) | 도출된 하위 부분 해답을 융합하여 상위 호출자의 정답으로 갱신 | 이진 탐색 등 특정 알고리즘에서는 이 결합 과정 자체가 생략됨 |

> 요약: 재귀 호출을 통해 분할을 거듭하여 기저 조건에서 문제를 풀고, 호출의 역순으로 리턴 결괏값을 병합하여 해를 완성하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
재귀 진입 -> 분할(N/2, N/2) -> Base Case 판별 -> 하위 트리 역순 연산 및 병합 -> 결과 리턴
```

- 1단계 [분할 조건 확인]: 입력 데이터 크기 N이 더 이상 연산 분리가 불가능한 임계치(Base Case)인지 점검
- 2단계 [하위 트리 분할]: 문제가 크다면 좌/우 등 독립된 N/b 크기로 분리 후 자신을 호출(Self-Call)하는 재귀 수행
- 3단계 [단위 문제 정복]: 더 쪼갤 수 없는 기저 상태에 도달 시 해당 요소 자체의 연산을 O(1)에 확정 처리
- 4단계 [결과 결합 반환]: 리턴 콜백에 맞춰 좌/우 등 하위 결괏값을 합치며, 최상위 부모 호출자에게 최종 배열 전달

> 요약: 탑다운(Top-Down)으로 문제를 조각내며 바닥을 찍은 뒤, 바텀업(Bottom-Up)으로 리턴과 함께 결과를 합쳐 최종 답을 만든다.

---

## Ⅳ. 특징
- 병렬화(Parallelism) 특화: 부분 문제 간 의존성(Dependency)이 전무하므로 멀티스레드 기반 분산 시스템의 Task 분배 처리 효율 압도적 우위
- 함수 콜 오버헤드: 재귀 함수를 매우 깊게 호출하므로 Call Stack 메모리 점유율이 높고 탈출 조건 누락 시 스택 오버플로우 장애 발생
- 수학적 예측 용이성: 마스터 정리(Master Theorem) `T(N) = aT(N/b) + f(N)` 공식을 통해 분할 비율에 따른 수행 시간을 정량적으로 예측 가능

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 분할 정복 (Divide & Conquer) | 동적 프로그래밍 (DP) | 탐욕 알고리즘 (Greedy) |
|:---|:---|:---|:---|
| 하위 문제 성질 | 상호 독립적 (Non-Overlapping) | 중복 및 반복 (Overlapping) | 국소적 시야의 현재 종속 |
| 접근 흐름 | Top-Down (재귀 호출 중심) | Bottom-Up / Top-Down 혼합 | 현재 시점 단방향 선택 전진 |
| 대표적 응용 | 병합 정렬, 퀵 정렬, 이진 탐색 | 최장 공통 부분 수열(LCS), 최단 경로 | 다익스트라, 허프만 코딩 압축 |

> 요약: 하위 문제가 겹치지 않는 명확한 경계를 가지면 분할 정복을, 상태가 겹쳐 저장소가 필요하다면 캐시를 쓰는 DP를 채택한다.

**리스크·대응:**
- 편향 트리로 인한 깊이 폭발: 퀵 정렬 시 피벗 선택 악화로 O(N) 깊이 재귀 발생 → 난수 기반 피벗 선택(Randomized Pivot) 적용으로 O(log N) 밸런스 유지
- 미세 단위 병합 오버헤드: 원소가 10개 미만으로 극소할 때 재귀 호출 함수 비용이 연산 효율 역전 → 임계치 도달 시 삽입 정렬(Insertion Sort)로 스위칭하는 Hybrid 전략 적용

**도입 후 점검 지표:**
- 처리량/성능 가속: 단일 스레드 처리 대비 Fork-Join 기반 멀티 코어 분할 적용 시 Speed-up Ratio(가속비) 타깃 달성도 확인
- 자원 안정성: 재귀 호출의 최대 도달 깊이(Max Depth)가 시스템 Stack 메모리 허용치의 20% 리밋을 초과하지 않는지 APM 모니터링

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대규모 분산 데이터 정렬: Hadoop / Spark 같은 빅데이터 처리 프레임워크에서 맵(Divide/Conquer)과 리듀스(Combine) 단계의 코어 알고리즘 모델링으로 적용
2. 고속 행렬 연산 모듈화: 쉬트라센(Strassen) 알고리즘을 적용해 컴퓨터 그래픽스 렌더링 파이프라인의 행렬 곱 O(N^3) 연산 부하를 O(N^2.81)로 대폭 단축
3. 고성능 병렬 프로그래밍 처리: Java Fork/Join 프레임워크 적용 시, 거대 태스크를 Work-Stealing 큐를 통해 반씩 쪼개어 가용 스레드 코어에 강제 분산 할당

**결론:**
- 기술사 판단: 분할 정복은 독립적 병렬 컴퓨팅 구현에 최적화된 패러다임이나, 문제의 성격에 중복 부분 구조가 존재할 경우 DP 대신 채택 시 엄청난 낭비가 발생하므로 사전 성질 판별이 필수다.
- 향후 방향: 모놀리식 단일 덩어리 구조를 수만 개의 마이크로 단위로 쪼개어 분산 정복하는 클라우드 네이티브 MSA 및 Serverless 아키텍처 설계 철학의 근간 이론으로 진화 중이다.
