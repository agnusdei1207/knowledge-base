# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 분할 정복은 큰 문제를 동일한 형태의 더 작은 **독립적** 하위 문제로 나눈(Divide) 뒤 각각을 해결하고(Conquer) 그 결과를 합쳐(Combine) 원래 문제의 답을 구하는 **재귀적 알고리즘 설계 기법**이다.
- **왜 필요한가**: 10만 건의 데이터를 한꺼번에 정렬하는 규칙을 바로 떠올리기는 어렵다. 하지만 1건짜리 조각으로 쪼개면 "1건은 이미 정렬된 상태"라는 자명한 기저 조건(Base Case)에 도달해, 그 단순한 조각들을 다시 합치기만 하면 된다.
- **핵심 직관**: 백과사전 편찬과 같다. 총괄 편집장이 10개 장으로 나누고, 각 팀장이 다시 절을 나누어 독립적으로 집필한 뒤, 마지막에 제본소에서 한 권으로 합친다.

## 핵심 용어 정리
| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 분할(Divide) | 문제를 더 작은 동일 형태의 부분 문제로 쪼개는 단계 | 책을 장·절로 나눔 |
| 정복(Conquer) | 더 이상 쪼갤 수 없는 기저 조건에 도달한 문제를 직접 해결하는 단계 | 한 문단을 실제로 집필 |
| 결합(Combine) | 해결된 하위 문제들의 답을 모아 원래 문제의 답으로 합치는 단계 | 완성된 장들을 제본해 한 권으로 |
| 기저 조건(Base Case) | 더 이상 분할하지 않고 즉시 답을 낼 수 있는 가장 작은 단위 | 원소 1개짜리 배열(이미 정렬됨) |
| 재귀 트리 | 분할이 반복되며 생기는 트리 형태의 호출 구조, 트리의 깊이와 각 층의 작업량이 전체 복잡도를 결정 | 나뭇가지처럼 뻗는 호출 계보 |
| 마스터 정리(Master Theorem) | `T(n) = aT(n/b) + f(n)` 형태의 재귀 점화식에서 시간복잡도를 바로 구하는 공식 | 재귀 복잡도 계산 치트키 |
| 균형 분할 | 문제를 항상 정확히 같은 크기로 나누는 방식(예: 병합 정렬의 절반씩) | 반으로 딱 나누기 |
| 불균형 분할 | 나누는 기준값(피벗)에 따라 크기가 들쭉날쭉해지는 방식(예: 퀵 정렬) | 임의 기준으로 나누다 보니 크기가 제각각 |

## 깊이 이해

### 왜 "독립적"이어야 하는가 — DP(013)와의 결정적 차이
분할 정복이 성립하려면 나뉜 하위 문제들이 서로 완전히 남남이어야 한다 — 왼쪽 절반의 답이 오른쪽 절반의 계산에 전혀 영향을 주지 않는다. 병합 정렬에서 배열의 왼쪽 절반을 정렬하는 작업과 오른쪽 절반을 정렬하는 작업은 서로 데이터가 겹치지 않는다. 이 독립성 덕분에 캐시(메모이제이션)가 필요 없고, 각 하위 문제를 서로 다른 CPU 코어나 서버에 던져 동시에 처리할 수 있다(MapReduce 등). 반대로 하위 문제가 반복해서 겹친다면(예: 피보나치) 분할 정복처럼 그냥 나눠 풀면 같은 계산을 몇 번이고 반복하게 되므로, 그때는 결과를 저장해 재사용하는 DP(013)로 바꿔야 한다.

### 병합 정렬로 보는 O(N log N) — 수치로 확인
길이 8인 배열을 병합 정렬한다고 하자. 분할 단계는 8→4→2→1로 매번 절반씩 줄어들며, 이 절반 나누기를 log₂(8)=3번 반복하면 원소 1개짜리 조각 8개에 도달한다(재귀 트리의 깊이가 log₂N). 각 깊이 층에서는 전체 원소를 다시 훑으며 병합(Combine)하는데, 그 비용의 합은 층마다 N(=8)이다. 따라서 총 비용은 "깊이(log N) × 층별 비용(N)" = O(N log N)이다. N=100만이라면 log₂(1,000,000)≈20이므로 약 2,000만 번의 비교로 끝나지만, O(N²) 방식(예: 삽입 정렬)이라면 1조 번에 가까운 연산이 필요하다 — 약 5만 배 차이다.

### 마스터 정리로 복잡도를 바로 읽는 법
`T(n) = a·T(n/b) + f(n)` 형태의 점화식에서 a는 재귀 호출 횟수, n/b는 매번 줄어드는 문제 크기, f(n)은 분할·결합에 드는 비용이다. 병합 정렬은 문제를 2개로 나누고(a=2) 각각 절반 크기(b=2)이며 결합에 O(n)이 들므로(f(n)=n), 마스터 정리 공식에 대입하면 O(n log n)이 나온다. 이진 탐색은 절반 크기(b=2)를 한쪽만 실질적으로 살펴보고(a=1) 결합 비용이 거의 없으므로(f(n)=O(1)) O(log n)이 나온다. 재귀 알고리즘의 복잡도를 직접 재귀 트리를 그리지 않고도 이 공식 하나로 바로 유도할 수 있다.

### 균형 분할 vs 불균형 분할 — 퀵 정렬이 최악에 무너지는 이유
병합 정렬은 항상 정확히 절반으로 나누므로 입력이 어떻든 O(N log N)을 보장한다. 반면 퀵 정렬은 피벗(기준값)을 기준으로 나누는데, 피벗이 항상 최소값이나 최대값으로 뽑히면(예: 이미 정렬된 배열에서 맨 앞 원소를 피벗으로 고정하는 구현) 한쪽 부분 문제의 크기가 N-1, 다른 쪽이 0이 되어버려 절반씩 줄어드는 대신 하나씩만 줄어든다. 이렇게 되면 재귀 깊이가 log N이 아니라 N이 되어 O(N²)로 악화된다. 실무에서는 피벗을 무작위로 고르거나 3개 값의 중앙값(3-median)을 쓰는 방식으로 이 최악의 경우가 나올 확률을 실질적으로 없앤다.

### 비유
피자 한 판을 한입에 먹을 수 없으니 조각조각 잘라(분할) 한 조각씩 먹고(정복), 그 조각들이 결국 뱃속에서 하나의 식사로 소화되는(결합) 과정과 같다.

### 흔한 오해
"문제를 잘게 쪼갤수록 무조건 빠르다"는 오해가 있지만, 분할 자체에도 비용이 든다. 원소 1개까지 무조건 재귀로 쪼개면 함수 호출 오버헤드가 누적되어 오히려 느려질 수 있어, 실무 구현(예: Tim Sort)은 배열 크기가 16~32 이하로 작아지면 재귀를 멈추고 상수가 작은 삽입 정렬로 전환하는 하이브리드 방식을 쓴다.

## 연결 개념
- 013 동적 프로그래밍 — 하위 문제가 겹치지 않는 분할 정복과, 겹치는 DP는 서로 대조되는 재귀 설계 전략
- 010 그래프 탐색 — 재귀 기반 DFS와 분할 정복의 재귀 구조는 형태적으로 유사(단, 목적과 분할 방식이 다름)
- 011 최단 경로 — 플로이드-워셜은 분할 정복이 아니라 DP 기반임을 대조해 구분하면 이해가 명확해짐

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 하향식 재귀 구조를 통해 거대 문제를 독립적이고 동일한 유형의 기저 문제로 분할-정복-결합하는 알고리즘 패러다임이다.
> 2. **가치**: $O(N^2)$ 복잡도의 문제를 로그 스케일의 분할 깊이(log N)와 병합(N) 연산으로 치환해 O(N log N)으로 응답 성능 한계를 돌파한다.
> 3. **판단 포인트**: 쪼개진 문제들이 상호 영향을 주지 않는 완전한 독립성을 가져야만 DP 캐싱 없이 병렬 스레드 분배(MapReduce 등)가 가능하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘 구조의 3단계 도식화 역량 확인 | Divide -> Conquer -> Combine 흐름과 재귀 조건 | 하위 문제가 독립적이라는 전제 조건을 누락하는 오류 |
| 동적 프로그래밍(DP)과의 구조적 변별력 | 중복 계산 부재, Top-down 구조, 병렬화 가능성 | 두 알고리즘이 문제를 쪼갠다는 공통점만 나열 |

> 요약: 분할 정복의 위력은 단순히 문제를 쪼개는 데 있는 것이 아니라, 결합 단계에서 복잡도를 보장하는 마스터 정리(Master Theorem) 모델에 있다.

## Ⅰ. 개요 및 필요성

- 정의: 해결하기 힘든 복잡한 문제를 동일한 형태의 기저 상태(Base Case)까지 분할한 후 해결 및 병합하는 재귀적 설계 기법
- 배경: 대용량 데이터 정렬 시 지수 폭발이 발생하여 선형 로그 형태의 복잡도 개선 구조 모색
- 필요성: 멀티코어 환경에서 데이터 청크를 독립적으로 연산 스레드에 던져주고 취합하는 병렬 컴퓨팅(MapReduce) 토대 확보

---

## Ⅱ. 구조 및 구성요소 (3단계 메커니즘)

```text
[입력 데이터 N] -> Divide(1/2 분할) -> Divide(1/4 분할) -> [Base Case 도착]
                                                           | 
[최종 병합 답안] <- Combine(병합 O(N)) <- Combine(병합) <- Conquer(해결 O(1))
```

| 구성요소 | 메커니즘 (역할) | 주요 제약 및 특징 |
|:---|:---|:---|
| 분할 (Divide) | 주어진 문제를 2개 또는 N개의 상호 독립적인 부분 문제로 쪼갬 | 분할 비용이 지나치게 크면 성능 저하 초래 |
| 정복 (Conquer) | 기저 조건에 도달한 문제를 직접 연산하여 해결 | 더 이상 분할 불가한 상태 식별 (배열 크기 1 도달) |
| 결합 (Combine) | 해결된 부분 문제의 해를 병합하여 본래 문제 해로 합성 | 전체의 시간복잡도를 지배하는 병목 구간 |

> 요약: 분할 정복은 하향(분할)과 상향(결합)이 쌍을 이루는 트리 구조를 형성하며, 모든 하위 문제는 독립적으로 실행된다.

---

## Ⅲ. 동작원리 및 병합 정렬(Merge Sort) 흐름도

```text
길이 8 배열 -> Left(4)/Right(4) 분할 재귀 -> 길이 1 배열 8개 도출(Conquer) 
            -> 2개 짝지어 크기 비교하며 결합(Merge) -> 길이 8 정렬 반환
```

| 단계 | 처리 내용 | 검증 기준 (시간 복잡도) |
|:---:|:---|:---|
| 1 | `Divide` | 배열의 중간 인덱스 `Mid = (L+R)/2` 산출 후 두 개의 서브 배열 분리 (O(1)) |
| 2 | `Conquer` (재귀) | 인덱스 L과 R이 같아질 때(원소 1개) 정렬이 완료된 것으로 취급 반환 (O(1)) |
| 3 | `Combine` | 반환된 좌/우 배열 포인터를 비교하여 임시 배열 공간에 오름차순 삽입 (O(N)) |
| 4 | 마스터 정리 (결과) | $\log_2 N$ 깊이의 트리마다 $N$번의 결합 연산 수행 $\rightarrow$ 총 $O(N \log N)$ 성능 달성 |

> 요약: 분할 연산 자체는 O(1)로 가볍지만, 실질적인 비교 로직은 Combine 단계에서 O(N)으로 집약된다.

## Ⅳ. 특징

| 구분 | 균형 분할 (Balanced, 예: Merge Sort) | 불균형 분할 (Unbalanced, 예: Quick Sort) | 판단 포인트 |
|:---|:---|:---|:---|
| 분할 기준 | 중간 인덱스로 항상 정확히 절반씩 분할 | 피벗(Pivot) 값 기준 분할, 크기가 입력 데이터 분포에 의존 | 입력 데이터의 정렬 상태·분포 예측 가능 여부 |
| 최악 시간복잡도 | 입력에 무관하게 O(N log N) 보장 | 피벗이 매번 최솟값/최댓값이면 $O(N^2)$로 악화 | 적대적(사전 정렬) 입력 가능성 |
| 추가 공간 | 병합용 O(N) 임시 버퍼 필요 | 대부분 인플레이스(in-place) 분할로 O(log N) 스택 공간만 필요 | 메모리 제약 환경 여부 |
| 실무 대응 | 성능 예측 가능성이 우선인 외부 정렬·병렬 정렬에 적합 | 피벗을 무작위/3-median 선택해 평균 O(N log N) 확보 | 최악 케이스 회피 전략 필요 여부 |

> 요약: 균형 분할은 입력에 관계없이 O(N log N)을 보장하지만 O(N) 추가 메모리를 요구하고, 불균형 분할은 공간 효율적이나 피벗 선택 전략에 성능이 좌우된다.

## Ⅴ. 주요 알고리즘 패러다임 심화 비교

| 구분 | 분할 정복 (Divide & Conquer) | 동적 계획법 (DP) | 탐욕 알고리즘 (Greedy) |
|:---|:---|:---|:---|
| 하위 문제 특성 | 상호 배타적 / 독립적 (Independent) | 의존적 / 중복 호출 발생 | 중복 없음 (매 단계 1개 선택 확정) |
| 접근 구조 | 하향식 (Top-down 재귀 중심) | 주로 상향식 (배열 중심) | 하향식 (미래 고려 없이 1차원 전진) |
| 병렬 처리 친화도 | 매우 높음 (스레드간 간섭 없음) | 낮음 (이전 연산이 다음 연산 락 점유) | 높음 (순차 처리 속도 극대화) |
| 대표 응용 | 병합 정렬, 퀵 정렬, 이진 탐색 | 최단경로 플로이드, 배낭 문제 | 다익스트라 최단경로, MST |

> 요약: 분할 정복의 최대 강점은 하위 문제가 "전혀 겹치지 않는다"는 점에 있으며, 이는 분산 처리를 위한 필수 아키텍처 조건이 된다.

| 리스크 | 발생 원인 | 대응 기법 (최적화) | 확인 지표 |
|:---|:---|:---|:---|
| 과도한 재귀 오버헤드 | Base Case(1)까지 무조건 재귀 분할 시 메모리 폭증 | 배열 크기가 16~32 이하로 작아지면 삽입 정렬 호출 (Tim Sort 방식) | 콜 스택 Depth 임계치 |
| 공간복잡도 한계 | 병합 정렬 시 결합 과정에서 O(N) 크기 임시 버퍼 필수 | 임시 배열 메모리 할당/해제 부하 최소화를 위한 인플레이스 머지 튜닝 | 피크 시 힙 메모리 할당량 |

> 요약: 분할 정복의 실무 리스크는 정확도가 아니라 재귀 오버헤드와 임시 버퍼 메모리이므로, 소규모 구간 하이브리드화와 인플레이스 튜닝으로 통제한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 빅데이터 분산 처리 (MapReduce): HDFS에 저장된 테라바이트 로그를 잘라(Divide) 각 노드에서 연산(Map)하고 그 결과를 리듀서 노드로 모아 결합(Reduce)
2. 고속 행렬 곱셈 연산: 그래픽 처리(GPU) 텐서 행렬 곱셈을 슈트라센(Strassen) 알고리즘 분할 정복으로 치환하여 $O(N^{2.81})$로 단축
3. 대용량 JSON 파싱: 대형 다큐먼트를 노드 단위로 분할하여 각각 독립적인 스레드 파서로 파싱 후 객체 트리를 결합하는 재귀 기반 구문 분석기 구성

**결론 (2줄):**
- 기술사 판단: 분할 정복은 단순 정렬 기법을 넘어 상호 독립적 태스크를 다중 코어와 분산 노드에 안전하게 할당하는 병렬 컴퓨팅 아키텍처의 논리 모델이다.
- 향후 방향: 클럭 속도 한계에 도달한 현대 CPU 구조에서는 멀티 스레드 활용률을 극대화하기 위해 Fork-Join 프레임워크 기반 분할 정복 로직이 스케줄러 표준으로 채택되었다.
