## 미리 알고가기

- 기저 조건: 더 이상 분할하지 않고 바로 답을 돌려주는 최소 문제 단위임
- 독립 부분 문제: 서로 계산 결과를 공유하지 않고 각각 따로 풀 수 있는 하위 문제임
- 결합 비용: 부분 해를 다시 모아 원문제의 답으로 만드는 데 드는 추가 연산임
- 고속 푸리에 변환(FFT): 신호나 다항식 계산을 작은 문제로 나눠 빠르게 처리하는 대표 분할 정복 알고리즘임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 큰 문제를 같은 형태의 더 작은 문제들로 나누고, 각 하위 문제를 독립적으로 해결한 뒤 결과를 다시 결합해 원문제의 답을 만드는 설계 기법임. 핵심은 나누기 자체가 아니라, 나눈 뒤에도 같은 규칙으로 계속 풀 수 있어야 한다는 점임
- **배경/필요성**: 큰 문제를 한 번에 처리하면 계산량과 구현 복잡도가 빠르게 커지므로, 하위 문제로 쪼개 각 부분을 단순하게 만든 뒤 다시 합치는 방식이 필요함

## Ⅱ. 특징

- 원문제를 같은 구조의 하위 문제로 반복해서 분해하므로 알고리즘 구조가 단순하고 재귀 구현이 자연스러움
- 하위 문제가 서로 독립적이면 병렬 처리로 확장하기 쉽고, 부분 결과를 동시에 계산할 수 있음
- 분할 이익이 결합 비용보다 커야 실제 성능 개선이 나타나므로 나누는 방식과 합치는 방식이 함께 중요함
- 하위 문제가 서로 겹치기 시작하면 분할 정복보다 동적 프로그래밍이 더 적합할 수 있으므로 문제 독립성 판단이 먼저 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 | 동적 프로그래밍 | 백트래킹 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 하위 문제가 서로 독립적이어서 같은 답을 공유하지 않음 | 같은 부분 문제가 반복되어 저장과 재사용이 필요함 | 가능한 선택 경로를 따라가며 가지치기를 수행함 |
| 핵심 처리 방식 | 문제를 나누고 각각 풀어 다시 결합함 | 상태 값을 저장하면서 이전 계산을 재사용함 | 후보를 하나씩 시도하다가 조건을 어기면 되돌아감 |
| 대표 장점 | 구조가 단순하고 병렬화하기 쉬움 | 중복 계산을 크게 줄일 수 있음 | 제약 조건이 강한 탐색 문제에서 불필요한 경로를 줄일 수 있음 |
| 대표 활용 | 병합 정렬, 퀵 정렬, 고속 푸리에 변환에 적합함 | 배낭 문제, 편집 거리, 최장 공통 부분 수열에 적합함 | 여왕 배치, 스도쿠, 조합 탐색 문제에 적합함 |

> 요약: 분할 정복은 하위 문제가 독립적일 때 가장 힘을 발휘하며, 중복 저장이나 제약 탐색이 중심인 방식과 구분됨

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분할 기준 | 문제를 어떤 규칙으로 나눌지 정하며, 이 기준이 한쪽으로 치우치면 하위 문제 크기가 충분히 줄지 않음 |
| 재귀 해결 단계 | 나뉜 하위 문제를 같은 방식으로 다시 푸는 단계이며, 더 이상 나눌 수 없을 때 멈출 기저 조건이 반드시 필요함 |
| 결합 단계 | 하위 문제의 답을 모아 상위 문제의 답으로 만드는 단계임. 이때 복사와 병합 비용이 크면 분할 효과가 줄어듦 |
| 시간복잡도 식 | 분할 수, 하위 문제 크기, 결합 비용을 식으로 표현한 값이며, 전체 알고리즘이 실제로 얼마나 빨라질지 판단하는 근거가 됨 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 원문제      | --> | 분할 기준    | --> | 하위 문제    | --> | 결합 단계    |
+-----------+     +-----------+     +-----------+     +-----------+
```

> 요약: 분할 정복 구조는 나누는 규칙, 재귀 처리, 결합 비용이 균형을 이룰 때만 기대 성능이 나옴

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 분할판단 | --> | 문제분할 | --> | 하위해결 | --> | 결과결합 |
+----------+     +----------+     +----------+     +----------+
```

1. **분할판단**: 현재 문제 크기가 기저 조건에 도달했는지 먼저 확인하고, 도달했으면 바로 답을 반환함
2. **문제분할**: 아직 크면 같은 유형의 더 작은 하위 문제들로 나눔
3. **하위해결**: 각 하위 문제를 같은 알고리즘으로 재귀 호출해 해결함
4. **결과결합**: 하위 결과를 병합하거나 조합해 상위 문제의 답으로 되돌림

## Ⅵ. 실무 적용 및 유의점

1. 외부 정렬은 큰 파일을 나눠 정렬한 뒤 다시 합치는 분할 정복이 맞지만 결합 비용이 커지면 이점이 줄어드므로 총 정렬 시간과 디스크 I/O로 확인함
2. 퀵 정렬처럼 분할이 한쪽으로 몰리면 속도가 급격히 나빠지므로 피벗 선택을 보강하고 분할 편차와 실행시간으로 확인함

## Ⅶ. 결론

분할 정복은 문제를 많이 쪼개는 기법이 아니라, 하위 문제를 균형 있게 나누고 결합 비용까지 함께 통제할 때 성능이 살아나는 기법임.
