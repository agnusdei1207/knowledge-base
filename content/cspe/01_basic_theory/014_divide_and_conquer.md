## 미리 알고가기

- 분할(Divide): 큰 문제를 동일한 구조의 작은 문제로 나누는 과정임
- 재귀 호출(Recursive Call): 처리 함수가 크기가 줄어든 부분 문제를 입력으로 자기 자신을 다시 호출하는 동작임
- 정복(Conquer): 각 부분 문제에 같은 함수를 다시 호출하고, 종료 조건에 도달하면 답을 직접 반환하는 과정임
- 결합(Combine): 부분 해를 합쳐 원래 문제의 해를 만드는 과정임
- 종료 조건(Base Case): 더 분할하지 않고 답을 직접 구하는 최소 입력 조건임
- 동적 계획법(DP): 반복되는 부분 문제의 답을 저장·재사용하는 알고리즘 설계 기법임

## 작성 근거(검토용)

- **개요 구성**: 분할 정복의 정의는 분할·정복·결합의 세 동작으로 충분하므로 이 흐름을 첫 문장에 배치함
- **Ⅱ. 특징 선정**: 동일 알고리즘 반복, 동시성·병렬성, 분할·결합 비용은 분할 정복의 핵심 동작과 적용 판단을 설명하므로 남김
- **Ⅲ. 비교축 선정**: 분할 정복과 동적 계획법의 중복 부분 문제·해 구성·저장 구조를 비교해 선택 기준을 드러냄
- **Ⅳ. 설계 요소 선정**: 절차와 중복되는 분할·정복·결합 나열을 제거하고 부분 문제 독립성·부분 문제 수·분할 균형도·종료 조건·결합 비용을 설계 판단 기준으로 배치함
- **Ⅴ. 절차 구성**: 종료 조건의 분기와 부분 해의 반환·결합을 표시하여 호출과 반환 방향을 구분함

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 큰 문제를 같은 구조의 작은 부분 문제로 나누어 재귀적으로 해결하고, 부분 해를 결합하는 설계 기법임
- **배경/필요성**: 문제 전체를 직접 해결하기 어렵더라도 동일한 구조의 작은 문제는 해결 가능한 경우, 부분 해로 전체 해를 구성하는 접근이 필요함

## Ⅱ. 특징

- 동일한 알고리즘을 크기가 줄어든 부분 문제에 반복 적용하고 종료 조건에서 부분 해를 반환함
- 각 부분 문제를 다른 부분 문제의 중간 결과 없이 해결할 수 있으면 병렬 처리 가능함
- 문제를 나누고 결과를 합치는 추가 비용이 동시성·병렬성의 효과를 좌우함

## Ⅲ. 동적 계획법과 비교

| 판단 기준 | 분할 정복 (Divide & Conquer) | 동적 계획법 (DP) |
|:---|:---|:---|
| 중복 부분 문제 | 같은 부분 문제가 다시 나타나면 별도 호출로 재계산 | 계산 결과를 저장·재사용해 중복 계산 제거 |
| 해 구성 | 재귀 호출로 구한 부분 해를 결합 | 선행 상태값으로 현재 상태값 계산 |
| 저장 구조 | 호출 스택과 결합용 임시 공간 | 메모이제이션 또는 테이블 |

> 요약: 재귀 호출로 구한 부분 해를 결합하면 분할 정복을, 반복되는 부분 문제의 결과를 재사용하면 동적 계획법을 적용함.

## Ⅳ. 설계 요소 및 성능 결정 기준

| 설계 요소 | 설명 |
|:---|:---|
| 부분 문제 독립성 | 부분 문제 해결 과정의 상호 비의존성 |
| 부분 문제 수 | 한 번의 분할에서 생성되는 부분 문제의 개수 |
| 분할 균형도 | 분할된 부분 문제의 입력 크기가 서로 비슷한 정도 |
| 종료 조건 | 입력이 직접 답을 구하도록 정한 처리 단위에 도달한 상태 |
| 결합 비용 | 부분 해를 전체 해로 합칠 때 추가로 소요되는 실행 시간과 저장 공간 |

> 요약: 부분 문제 해결 과정의 비의존성은 병렬화 가능성을, 부분 문제 수·분할 균형도·결합 비용은 실행 시간을 좌우함.

## Ⅴ. 원리 및 절차 흐름도

```text
종료 조건 판정
├─ 충족 → 직접 계산·반환
└─ 미충족 → 부분 문제 분할
                  ↓
            각 부분 문제 해결
                  ↓
            부분 해 결합·반환
```

1. **종료 조건 확인**: 종료 조건을 충족하면 답을 구해 반환함
2. **부분 문제 분할**: 종료 조건을 충족하지 않으면 입력을 동일한 구조의 작은 문제로 나눔
3. **동일 함수 호출**: 크기가 줄어든 각 부분 문제를 입력으로 같은 처리 함수를 호출함
4. **부분 해 결합·반환**: 각 호출이 반환한 부분 해를 합쳐 현재 문제의 답을 만들고 상위 호출로 반환함

> 요약: 호출 역순으로 부분 해를 결합함.

## Ⅵ. 실무 사례

1. 대용량 파일 정렬은 병합 정렬로 분할 처리하고 병합 I/O 횟수·임시 저장 공간으로 성능이 갈림
2. 퀵 정렬은 피벗 무작위화로 편향 분할을 줄이고 최대 연속 호출 횟수·호출 스택 사용량으로 스택 오버플로 위험을 가늠함

## Ⅶ. 결론

- 분할 정복은 큰 문제를 작은 문제로 나누어 해결하여 동시성·병렬성을 확보하는 기법이며, 분할 및 결합 비용을 고려해야 함
- 부분 문제가 독립적이고 작업 크기가 병렬 실행 비용보다 클 때 적용하며, 작은 작업은 순차 처리로 전환해야 함
