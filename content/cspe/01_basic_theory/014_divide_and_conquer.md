## 미리 알고가기

- 기저 조건: 더 이상 분할하지 않고 바로 답을 돌려주는 최소 문제 단위임
- 독립 부분 문제: 서로 계산 결과를 공유하지 않고 각각 따로 풀 수 있는 하위 문제임
- 결합 비용: 부분 해를 다시 모아 원문제의 답으로 만드는 데 드는 추가 연산임
- 고속 푸리에 변환(FFT, Fast Fourier Transform): 신호나 다항식 계산을 작은 문제로 나눠 빠르게 처리하는 대표 분할 정복 알고리즘임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 큰 문제를 같은 형태의 더 작은 문제들로 나누고, 각 하위 문제를 독립적으로 해결한 뒤 결과를 다시 결합해 원문제의 답을 만드는 설계 기법임. 핵심은 나누기 자체가 아니라, 나눈 뒤에도 같은 규칙으로 계속 풀 수 있어야 한다는 점임
- **배경/필요성**: 큰 문제를 한 번에 처리하면 계산량과 구현 복잡도가 빠르게 커지므로, 하위 문제로 쪼개 각 부분을 단순하게 만든 뒤 다시 합치는 방식이 필요함

## Ⅱ. 특징

- 원문제를 같은 구조의 하위 문제로 반복해서 분해하므로 알고리즘 구조가 단순하고 재귀 구현이 자연스러움
- 하위 문제가 서로 독립적이면 병렬 처리로 확장하기 쉽고, 부분 결과를 동시에 계산할 수 있음
- 분할 이익이 결합 비용보다 커야 실제 성능 개선이 나타나므로 나누는 방식과 합치는 방식이 함께 중요함
- 하위 문제가 서로 겹치기 시작하면 분할 정복보다 동적 프로그래밍이 더 적합할 수 있으므로 문제 독립성 판단이 먼저 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 | 동적 프로그래밍 | 백트래킹 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 하위 문제가 서로 독립적이어서 같은 답을 공유하지 않음 | 같은 부분 문제가 반복되어 저장과 재사용이 필요함 | 가능한 선택 경로를 따라가며 가지치기를 수행함 |
| 핵심 처리 방식 | 문제를 나누고 각각 풀어 다시 결합함 | 상태 값을 저장하면서 이전 계산을 재사용함 | 후보를 하나씩 시도하다가 조건을 어기면 되돌아감 |
| 대표 장점 | 구조가 단순하고 병렬화하기 쉬움 | 중복 계산을 크게 줄일 수 있음 | 제약 조건이 강한 탐색 문제에서 불필요한 경로를 줄일 수 있음 |
| 대표 활용 | 병합 정렬, 퀵 정렬, 고속 푸리에 변환에 적합함 | 배낭 문제, 편집 거리, 최장 공통 부분 수열에 적합함 | 여왕 배치, 스도쿠, 조합 탐색 문제에 적합함 |

> 요약: 분할 정복은 하위 문제가 독립적일 때 가장 힘을 발휘하며, 중복 저장이나 제약 탐색이 중심인 방식과 구분됨

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원문제 | 분할 전 크기 $n$의 입력 전체이며, 분할 기준과 하위 문제 개수를 정하는 출발점임 |
| 분할 함수 | 원문제를 크기 $n/b$인 하위 문제 $a$개로 나누고, $a$와 $b$ 값이 하위 문제 개수와 크기 비율을 함께 정함 |
| 기저 조건 | 하위 문제 크기가 더 이상 나눌 필요가 없을 만큼 작아졌을 때 즉시 답을 반환하는 재귀 종료 지점임 |
| 하위 문제(독립 부분 문제) | 서로 값을 공유하지 않고 각각 재귀로 해결되므로 처리 순서를 바꾸거나 동시에 계산할 수 있음 |
| 결합 함수 | 하위 문제의 답을 원문제의 답으로 합치며, 이 단계의 처리 비용 $f(n)$이 전체 시간복잡도의 크기를 좌우함 |

```text
                 +----------+
                 | 원문제 n |
                 +----------+
                       |
                       v
   +----------+   +----------+   +----------+
   | 하위문제1 |   | 하위문제2 |   | 하위문제a |
   | (n/b)    |   | (n/b)    |   | (n/b)    |
   +----------+   +----------+   +----------+
        |              |              |
        v              v              v
   +----------------------------------------+
   |              결합 함수                  |
   +----------------------------------------+
                       |
                       v
                 +----------+
                 | 원문제 답 |
                 +----------+
```

> 요약: 원문제가 독립된 하위 문제 $a$개로 갈라졌다가 결합 함수에서 다시 하나의 답으로 모이는 트리 구조가 분할 정복의 뼈대임

## Ⅴ. 원리 및 절차 흐름도

```text
+------------+     +----------+     +----------+     +----------+
| 입력크기확인 | --> | 분할     | --> | 재귀정복  | --> | 결합     |
+------------+     +----------+     +----------+     +----------+
      |
      | (기저조건 충족 시)
      v
 +----------+
 | 즉시반환  |
 +----------+
```

1. **입력 크기 확인**: 현재 하위 문제 크기가 기저 조건을 만족하는지 먼저 판별함
2. **분할**: 기저 조건을 만족하지 않으면 원문제를 크기 $n/b$인 하위 문제 $a$개로 나눔
3. **재귀 정복**: 각 하위 문제를 같은 절차로 독립 재귀 호출해 해결하며, 이 지점에서 하위 문제 간 순서를 바꾸거나 병렬로 실행할 수 있음
4. **결합**: 하위 해를 모아 원문제 답을 만들며, 재귀 관계식 $T(n) = aT(n/b) + f(n)$에서 $f(n)$이 클수록 전체 복잡도가 결합 단계에 좌우됨. 이때 마스터 정리(Master Theorem)로 $a$, $b$, $f(n)$의 관계를 비교해 전체 시간복잡도를 판정함

## Ⅵ. 실무 적용 및 유의점

1. 병합 정렬이나 고속 푸리에 변환처럼 하위 문제가 독립적인 대규모 데이터 처리에는 분할 정복이 적합하지만 재귀 호출이 깊어지면 시스템 한계를 넘을 수 있으므로 깊이가 큰 입력은 반복문 기반 상향식 구현으로 바꾸고 최대 재귀 깊이와 스택 사용량으로 확인함
2. 입력 크기가 작아질수록 재귀 호출과 결합 처리 오버헤드가 실제 이득보다 커지므로 퀵 정렬 같은 알고리즘은 임계 크기 이하 구간을 삽입 정렬 같은 기본 알고리즘으로 전환하고 전체 실행 시간과 재귀 호출 횟수로 확인함

## Ⅶ. 결론

분할 정복은 하위 문제가 서로 독립적이어서 재귀로 병렬 해결할 수 있고 분할 이익이 결합 비용을 넘어서는 경우에만 선택해야 하는 기법임.
