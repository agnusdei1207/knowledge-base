## 미리 알고가기

- 기저 조건: 더 이상 분할하지 않는 최소 문제 단위임
- 독립 부분 문제: 서로 계산 결과를 공유하지 않는 하위 문제임
- 결합 비용: 부분 해를 다시 합치는 데 드는 추가 연산임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 큰 문제를 독립적인 작은 문제로 나누고, 각각을 해결한 뒤 결과를 결합해 원문제 답을 만드는 설계 기법임
- **배경/필요성**: 단일 문제를 한 번에 처리하면 계산량이 커지는 경우가 많으므로, 구조적으로 쪼개 병렬성과 로그 단계 축소 효과를 얻는 방식이 필요함

## Ⅱ. 특징

- 부분 문제가 독립적이어서 병렬 처리와 재귀적 구현에 잘 맞음
- 핵심은 단순 분할이 아니라 결합 비용보다 분할 효과가 커야 한다는 점임
- 병합 정렬, 퀵 정렬, FFT처럼 구조가 반복되는 문제에서 강력함
- 부분 문제가 중복되면 DP로 바뀌어야 하므로 문제 독립성 판단이 먼저임

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 | 동적 프로그래밍 | 백트래킹 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 독립적 | 중복적 | 가지치기 탐색 |
| 핵심 연산 | 분할-해결-결합 | 상태 저장-재사용 | 유망성 검사 |
| 강점 | 병렬성, 구조 단순성 | 중복 계산 제거 | 탐색 공간 축소 |
| 대표 문제 | 병합 정렬, FFT | 배낭 문제, LCS | N-Queen |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분할 규칙 | 문제를 어떤 기준으로 쪼갤지 정하고 균형 분할 여부가 성능에 영향 줌 |
| 정복 단계 | 하위 문제를 재귀적으로 해결하고 기저 조건이 반드시 필요함 |
| 결합 단계 | 부분 해를 다시 합쳐 최종 답을 만듦 여기서 병목이 생기기 쉬움 |
| 점화식 | 전체 비용을 식으로 표현하고 성능 예측 근거가 됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 문제분할 | --> | 하위해결 | --> | 결과결합 | --> | 종료반환 |
+----------+     +----------+     +----------+     +----------+
```

1. **문제분할**: 원문제를 같은 유형의 작은 문제들로 나눔
2. **하위해결**: 각 부분 문제를 같은 알고리즘으로 재귀 해결함
3. **결과결합**: 부분 해를 병합하거나 조합해 상위 문제 답을 만듦
4. **종료반환**: 기저 조건에서 직접 답을 반환하고 상위로 복귀함

## Ⅵ. 문제점 및 해결 방안

1. **분할이 불균형해짐**: 퀵 정렬처럼 한쪽으로 치우치면 성능이 급락함
   - **해결 방안**: 피벗 개선이나 균형 분할 전략을 적용하고 분할 편차로 검증함
2. **결합 단계가 병목이 됨**: 병합 비용이 크면 분할 효과가 상쇄됨
   - **해결 방안**: 결합 연산의 복사량과 메모리 접근을 최적화하고 결합 시간 비중로 검증함
3. **재귀 깊이가 커짐**: 스택 사용량 증가와 함수 호출 오버헤드가 누적됨
   - **해결 방안**: 작은 구간은 반복문이나 단순 알고리즘으로 전환하고 최대 재귀 깊이로 검증함

## Ⅶ. 적용 사례

- 외부 정렬: 병합 정렬로 큰 파일을 나눠 정렬 후 결합함, 확인 지표는 총 정렬 시간과 디스크 I/O임
- 영상 신호 처리: FFT로 주파수 영역 변환을 수행함, 확인 지표는 처리량과 계산 정확도임
- 병렬 연산 프레임워크: 독립 작업을 분할해 병렬 실행함, 확인 지표는 작업 완료 시간과 코어 활용률임

## Ⅷ. 결론

분할 정복은 문제를 얼마나 잘 나누느냐보다 나눈 뒤 결합 비용까지 통제할 수 있느냐가 실제 성능을 결정함.
