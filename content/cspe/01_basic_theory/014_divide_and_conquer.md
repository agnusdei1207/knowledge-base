## 미리 알고가기

- 분할: 큰 문제를 같은 형태의 더 작은 부분 문제로 나누는 단계임
- 정복: 부분 문제를 직접 풀거나 재귀적으로 해결하는 단계임
- 결합: 부분 문제의 결과를 모아 전체 문제의 답을 만드는 단계임
- 기저 조건: 더 이상 나누지 않고 바로 답을 낼 수 있는 최소 문제 조건임
- 재귀식: 문제 크기 감소와 결합 비용을 표현한 비용 관계식임

## Ⅰ. 개요

- **정의**: 분할 정복은 큰 문제를 독립적인 하위 문제로 나누어 해결하고 결과를 결합해 전체 해를 구하는 알고리즘 설계 기법임
- **배경/필요성**: 큰 입력을 한 번에 처리하면 비교·연산 횟수가 입력 크기의 제곱 이상으로 커지는 문제가 많으므로, 문제를 작은 부분으로 나눠 풀고 결합해 전체 비용을 낮추는 설계 기법이 필요해짐. 다만 부분 문제가 반복적으로 겹치면 동적 프로그래밍(Dynamic Programming, DP)이, 결합 없이 국소 선택으로 충분하면 탐욕 알고리즘(Greedy Algorithm)이 더 적합함.
- **비유**: 큰 보고서를 장별로 나눠 각각 작성한 뒤 편집자가 하나의 문서로 합치는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘 설계 패턴 이해 확인 | 분할, 정복, 결합, 기저 조건, 재귀식 | DP와 혼동, 결합 비용 누락 |

> 요약: 분할 정복은 독립적인 부분 문제를 재귀적으로 해결하고 결합해 전체 답을 만드는 설계 기법임.

## Ⅱ. 특징/비교

| 판단 기준 | 분할 정복 | 동적 프로그래밍 | 탐욕 알고리즘 |
|:---|:---|:---|:---|
| 부분 문제 관계 | 대체로 독립적 | 중복 부분 문제가 많음 | 부분 문제를 명시적으로 저장하지 않음 |
| 결과 생성 | 부분 해를 결합 | 상태값을 재사용 | 국소 선택을 누적 |
| 대표 사례 | 병합 정렬, 퀵 정렬, 이진 탐색 | 배낭, 최단 편집거리 | MST(Minimum Spanning Tree), 허프만 코딩 |
| 비용 판단 | 재귀식과 결합 비용 | 상태 수와 전이 수 | 선택 증명과 자료구조 비용 |
| 선택 기준 | 균형 분할과 결합 가능성 | 중복 계산 제거 필요 | 선택 순간의 최적성이 보장될 때 |

> 요약: 분할 정복은 부분 문제가 겹치지 않고 결합 구조가 명확할 때 적합한 설계 전략임.

- 균형 분할은 재귀 깊이를 낮춰 `O(log n)` 단계 구조를 만들 수 있음
- 결합 단계가 비싸면 분할 효과가 상쇄되므로 전체 재귀식을 함께 봐야 함
- 병렬 처리에서는 부분 문제가 독립적이어서 코어·노드별로 동시에 계산을 배분할 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 원문제   | ---> | 부분문제 | ---> | 부분해   |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 기저조건 |      | 재귀호출 |      | 결합결과 |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 원문제 | 해결해야 할 전체 입력과 목표를 가진 문제임 | 전체 보고서 |
| 분할 규칙 | 입력을 더 작은 같은 형태의 문제로 나누는 기준임 | 장별 분담 |
| 기저 조건 | 재귀를 멈추고 즉시 답을 낼 수 있는 최소 입력 조건임 | 한 문단 초안 |
| 정복 결과 | 각 부분 문제가 산출한 부분 해임 | 장별 원고 |
| 결합 함수 | 부분 해를 전체 해로 합치는 처리 로직임 | 최종 편집 |

> 요약: 분할 정복은 분할 규칙과 기저 조건으로 재귀 구조를 만들고 결합 함수로 전체 결과를 완성함.

- 분할 결과가 원문제와 같은 형태여야 재귀적 해결이 자연스럽게 성립함
- 기저 조건이 불명확하면 재귀가 종료되지 않거나 잘못된 값을 반환할 수 있음
- 결합 함수는 정렬 병합처럼 핵심 비용이 될 수 있으므로 별도 분석이 필요함

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 문제확인 | ---> | 분할수행 | ---> | 정복수행 | ---> | 결합반환 |
+----------+      +----------+      +----------+      +----------+
      |                 |                 |                 |
      v                 v                 v                 v
+----------+      +----------+      +----------+      +----------+
| 기저판정 |      | 크기축소 |      | 재귀/직접|      | 전체해   |
+----------+      +----------+      +----------+      +----------+
```

1. **입력/요구 식별** - 문제를 같은 형태의 작은 문제로 나눌 수 있는지, 결합 결과가 원문제의 해가 되는지 확인함
2. **분할과 기저 판정** - 입력 크기가 충분히 작으면 직접 풀고, 아니면 균형 있게 부분 문제로 나눔
3. **부분 문제 정복** - 각 부분 문제를 재귀 호출 또는 직접 계산으로 해결함
4. **결합과 반환** - 부분 해를 정렬, 병합, 비교, 합산해 전체 해를 만들고 재귀식을 기준으로 비용을 산정함

> 요약: 분할 정복 절차는 기저 조건까지 문제를 줄이고, 부분 해를 결합해 전체 결과를 반환하는 흐름임.

- 퀵 정렬은 분할 단계의 피벗 선택이 성능을 좌우하고, 병합 정렬은 결합 단계의 병합 비용이 핵심임
- 이진 탐색은 한쪽 부분 문제만 선택하는 특수한 분할 정복으로 볼 수 있음
- 마스터 정리는 일정한 형태의 재귀식 비용을 빠르게 판단하는 도구임

## Ⅴ. 문제점

- **P1 불균형 분할**: 입력이 한쪽으로 치우치면 재귀 깊이가 커져 시간 복잡도와 스택 사용량이 악화됨
- **P2 결합 비용 과소평가**: 부분 문제를 빠르게 풀어도 결합 단계가 `O(n)` 이상이면 전체 비용의 병목이 될 수 있음
- **P3 중복 부분 문제 방치**: 같은 부분 문제가 반복해서 나타나는 문제에 분할 정복만 적용하면 불필요한 재계산이 증가함

> 요약: 분할 정복의 실패는 분할 균형, 결합 비용, 부분 문제 중복을 잘못 판단할 때 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 무작위 피벗, median-of-three, 균형 분할 기준을 적용하고 최대 재귀 깊이를 제한함 (확인: 최악 입력 테스트)
- **P2 대응**: 재귀식에 결합 비용을 명시하고 병합 단계 자료구조와 메모리 사용량을 최적화함 (확인: 단계별 수행시간)
- **P3 대응**: 중복 부분 문제가 확인되면 메모이제이션이나 bottom-up DP로 전환함 (확인: 동일 상태 재방문 횟수)

> 요약: 분할 정복 개선은 균형 분할을 보장하고 결합 비용을 모델링하며 중복 문제는 DP로 전환하는 것임.

## Ⅶ. 전망

- **발전 방향**: 멀티코어와 분산 처리 환경에서 독립 부분 문제를 병렬 실행하는 분할 정복 패턴은 계속 중요해짐
- **기술사적 판단**: 분할 정복을 적용할 때는 재귀식과 결합 비용을 함께 제시해 실제 복잡도 판단을 보여야 함
- **기술사 제언**: 답안에서는 `분할-정복-결합`을 쓰는 데서 멈추지 말고, 부분 문제가 독립인지 중복인지로 DP와 구분해야 함
