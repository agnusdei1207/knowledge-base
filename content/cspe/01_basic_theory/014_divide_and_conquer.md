## 미리 알고가기

- 분할(Divide): 해결하기 어려운 큰 문제를 동일한 성격의 작은 부분 문제들로 쪼개는 과정임
- 정복(Conquer): 분할된 부분 문제를 동일 알고리즘으로 해결하고, 최소 단위에서는 직접 답을 반환하는 과정임
- 통합(Combine): 정복된 부분 문제들의 해를 결합하여 원래 문제의 최종 해를 도출하는 과정임
- 재귀(Recursion): 동일 구조의 부분 문제를 자연스럽게 표현하는 대표 구현 방식임
- 점화식: 입력 크기별 하위 문제 개수, 축소 비율, 결합 비용을 함께 나타내는 비용 표현식임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 동일 구조의 문제를 독립적인 하위 문제로 나누고, 각 부분 문제를 재귀적 또는 반복적으로 해결한 뒤 결합 비용까지 포함해 전체 해를 구성하는 설계 전략임
- **배경/필요성**: 정렬, 탐색, 기하 계산처럼 입력 규모가 커질수록 직접 처리 비용이 커지는 문제에서는 균형 분할과 낮은 결합 비용을 이용해 전체 처리 비용을 줄이는 구조가 필요함

## Ⅱ. 특징

- 하위 문제가 서로 겹치지 않고 독립적이면 중복 계산을 줄이고 병렬 실행 후보를 만들 수 있지만, 분할이 불균형하거나 결합 비용이 크면 이점이 줄어듦
- 균등 분할 구조에서는 전체 비용을 $T(n)=aT(n/b)+f(n)$ 형태로 표현할 수 있으며, $a$는 하위 문제 수, $b$는 축소 비율, $f(n)$은 분할·결합 비용을 의미함
- 재귀 깊이와 결합 비용이 전체 실행 시간과 스택 사용량을 결정하므로, 분할 기준과 종료 조건을 함께 설계해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 (Divide & Conquer) | 동적 프로그래밍 (DP) |
|:---|:---|:---|
| **부분 문제 관계** | 서로 독립적이고 중복이 적음 | 중복 부분 문제가 반복됨 |
| **처리 방식** | 분할, 부분 문제 해결, 결합 | 상태값 저장 후 재사용 |
| **핵심 기법** | 재귀 호출, 작업 큐, 결합 연산 | 메모이제이션, 타뷸레이션 |
| **성능 병목** | 불균형 분할, 결합 비용, 재귀 깊이 | 상태 수, 전이 비용, 저장 공간 |
| **대표 사례** | 병합 정렬, 퀵 정렬, 이진 탐색 | 플로이드-워셜, 배낭 문제, 피보나치 |

> 요약: 부분 문제가 독립적이고 균형 분할·결합 비용이 유리하면 분할 정복을, 중복 상태를 저장해 재사용해야 하면 동적 프로그래밍을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분할 논리 | 문제를 어떤 기준으로, 몇 개의 부분 문제로 나눌지 결정하는 분기 로직임 |
| 기저 사례 (Base Case) | 더 이상 분할할 필요가 없는 가장 작은 문제의 상태이며, 재귀 호출의 탈출 조건임 |
| 정복 로직 | 각 부분 문제에 동일한 알고리즘을 적용하거나 기저 사례에서 직접 답을 반환하는 해결 절차임 |
| 결합 연산 | 분할된 영역에서 산출된 부분 해들을 논리적으로 병합하여 상위 문제의 해로 만드는 과정임 |
| 제어 흐름 | 재귀 구현은 호출 스택, 병렬 구현은 작업 큐나 스케줄러로 부분 문제 실행 순서를 제어함 |

```text
[ 분할 정복 처리 흐름 ]
        Problem P
        /       \
   Subproblem  Subproblem
       |           |
   Solution A  Solution B
        \       /
      Combined Solution
```

> 요약: 분할 기준, 기저 사례, 정복 로직, 결합 연산이 함께 맞아야 부분 해가 원래 문제의 해로 회수됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------------+     +----------------+     +----------------+     +----------------+
| 종료 조건 확인 | --> | 부분 문제 분할 | --> | 부분 문제 해결 | --> | 결합/비용 확인 |
+----------------+     +----------------+     +----------------+     +----------------+
```

1. **종료 조건 확인** — 입력 문제가 직접 해결 가능한 기저 사례인지 확인하고, 해당하면 즉시 답을 반환함
2. **부분 문제 분할** — 문제가 여전히 크면 동일 구조의 독립적인 작은 문제로 나누고 분할 균형을 확인함
3. **부분 문제 해결** — 나뉜 각 부분 문제에 동일 알고리즘을 적용해 부분 해를 구함
4. **결합/비용 확인** — 부분 해를 결합 규칙에 따라 합치고, 분할·해결·결합 비용이 점화식 기준에 맞는지 확인함

> 요약: 분할 정복은 종료 조건을 먼저 고정하고, 분할 균형과 결합 비용을 통제할 때 재귀 비용을 예측할 수 있음.

## Ⅵ. 실무 적용 및 유의점

1. 부분 문제가 서로 독립적이지 않고 결과값을 공유하는 문제에 분할 정복을 적용하면 중복 호출이 늘어나므로, 호출 횟수와 실행 시간 프로파일을 확인해 필요하면 동적 프로그래밍으로 전환해야 함
2. 퀵 정렬처럼 분할이 한쪽으로 치우치면 재귀 깊이가 커져 스택 오버플로가 발생할 수 있으므로, 피벗 무작위화나 반복 구현을 적용하고 최대 재귀 깊이와 스택 사용량으로 안정성을 확인해야 함

## Ⅶ. 결론

- 분할 정복은 독립적인 동일 구조 문제를 균형 있게 나누고 결합 비용을 통제할 때 효과가 있으므로, 점화식과 재귀 깊이를 기준으로 적용 여부를 판단해야 함
