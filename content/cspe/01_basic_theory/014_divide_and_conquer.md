# 분할 정복 (Divide and Conquer)

## 미리 알고가기

- **재귀(recursion)**: 큰 문제를 풀 때 "똑같은 방법으로 더 작은 문제를 풀어라"고 자기 자신을 다시 부르는 방식. 문제가 충분히 작아지면(기저 조건) 부르기를 멈춘다.
- **점화식(recurrence)**: `T(n) = a·T(n/b) + f(n)` 처럼, 크기 `n` 문제의 비용을 "쪼갠 조각들의 비용 + 합치는 비용"으로 적은 식. 분할 정복의 실제 속도는 이 식을 풀어 나온다.

## 1. 개요

- **정의/개념**: 분할 정복은 하나의 큰 문제를 서로 겹치지 않는 작은 문제 여러 개로 쪼개(분할), 각 조각을 같은 방법으로 재귀해 풀고(정복), 그 부분 답들을 다시 하나로 합쳐(결합) 전체 답을 만드는 알고리즘 설계 방식이다.
- **배경/필요성**: 크기 `n`짜리 문제를 한 덩어리로 훑으면 대개 `O(n^2)`처럼 비용이 가파르게 오른다. 그런데 문제를 절반씩 쪼개면 한 단계를 내려갈 때마다 크기가 반으로 줄어 단계 수가 `log n`밖에 안 되고, 각 단계에서 조각을 합치는 일만 잘 처리하면 전체가 `O(n log n)`으로 내려간다. 정렬을 예로 들면, 통째로 비교하는 방식은 `n`이 100배가 되면 시간이 만 배로 뛰지만, 절반씩 쪼개 병합하면 백 배를 조금 넘는 선에서 끝난다. 이렇게 "쪼개면 단계가 짧아진다"는 성질을 쓰는 것이 분할 정복이다.

## 2. 특징 및 비교

분할 정복이 빛나려면 세 가지 조건이 맞아야 한다. 쪼갠 조각들이 서로 답을 공유하지 않고 **독립**이어야 하고, 조각 크기가 **균형** 있게 갈라져야 하며, 부분 답을 합치는 **결합** 비용이 너무 크지 않아야 한다. 이 조건이 깨지는 지점이 곧 다른 설계 기법과 갈라지는 지점이다.

| 구분 | 분할 정복 | 동적 프로그래밍(DP) | 탐욕(Greedy) |
|:---|:---|:---|:---|
| 부분 문제 관계 | 서로 독립, 겹치지 않음 | 같은 부분 문제가 반복해 겹침 | 부분 문제를 나누기보다 매 순간 최선을 고름 |
| 핵심 동작 | 분할 → 재귀 → 결합 | 겹치는 답을 표에 저장(메모이제이션) | 국소 최적을 하나씩 확정 |
| 대표 예 | 병합 정렬, 퀵 정렬, 이진 탐색 | 배낭 문제, 최장 공통 부분수열(LCS) | 최소 신장 트리(MST), 허프만 코딩 |
| 주로 깨지는 곳 | 분할 불균형, 결합 병목 | 저장할 상태가 폭발 | 국소 최선이 전체 최선이 아님 |

> 요약: 조각이 겹치면 DP, 매 순간 확정해도 되면 탐욕, 겹치지 않게 쪼개 합치면 분할 정복이다.

DP와의 구분이 특히 중요하다. 피보나치를 그냥 재귀로 풀면 `F(n-1)`과 `F(n-2)`가 아래에서 같은 값을 수없이 다시 계산한다. 이렇게 조각이 겹치는 문제에 분할 정복을 그대로 쓰면 같은 일을 반복해 지수 시간으로 터지므로, 이때는 답을 저장해 재사용하는 DP로 옮겨야 한다. 반대로 병합 정렬처럼 왼쪽 절반과 오른쪽 절반이 서로 남의 답을 볼 일이 전혀 없으면 분할 정복이 맞다.

## 3. 구성요소/구조

```text
        [ 큰 문제 n ]
          /      \        <- 분할(Divide): 절반씩 쪼갬
   [ n/2 ]      [ n/2 ]
    /   \        /   \     <- 정복(Conquer): 같은 방법으로 재귀
  ...   ...    ...   ...
   |                 |     <- 기저 조건: 크기 1이면 그대로 답
    \       /   \    /
     [부분 답] [부분 답]    <- 결합(Combine): 합쳐서 위로 올림
          \      /
        [ 전체 답 ]
```

| 구성요소 | 하는 일 | 왜 중요한가 |
|:---|:---|:---|
| 분할(Divide) | 문제를 작은 하위 문제로 쪼갬 | 절반씩 균형 있게 갈라야 단계가 `log n`으로 짧아짐 |
| 정복(Conquer) | 각 조각을 재귀로 풀거나, 충분히 작으면 직접 풂 | 같은 규칙을 아래로 그대로 적용 |
| 결합(Combine) | 부분 답을 합쳐 상위 답을 만듦 | 이 비용 `f(n)`이 전체 복잡도를 좌우 |
| 기저 조건 | 더 쪼개지 않는 최소 문제(크기 1 등) | 없으면 재귀가 멈추지 못해 무한 반복 |

> 요약: 분할이 단계 수를, 결합이 단계별 비용을 정하므로, 전체 속도는 이 둘의 곱으로 결정된다.

전체 비용은 점화식 `T(n) = a·T(n/b) + f(n)`으로 정리되고, 여기서 `a`는 몇 조각으로 나누는지, `n/b`는 각 조각의 크기, `f(n)`은 합치는 비용이다. 병합 정렬은 두 조각(`a=2`)으로 반씩(`b=2`) 나눈 뒤 합칠 때 `O(n)`이 들어 `T(n)=2T(n/2)+O(n)`, 이를 풀면 `O(n log n)`이 된다. 이처럼 분할 정복의 성능은 감이 아니라 이 식에서 계산되어 나온다.

## 4. 문제점 및 개선방안

1. **분할이 한쪽으로 쏠림(불균형)**: 퀵 정렬에서 이미 정렬된 입력에 맨 끝 값을 기준(피벗)으로 잡으면, 매번 한 조각이 크기 0이고 다른 조각이 거의 전부가 된다. 이러면 단계가 `log n`이 아니라 `n`까지 늘어나 `O(n^2)`으로 떨어진다.
   - **개선방안**: 피벗을 무작위로 뽑거나 세 값의 중앙값으로 잡아 조각이 반씩 갈리게 만든다. (확인: 최악에도 재귀 깊이 `O(log n)` 유지)

2. **결합 단계가 병목**: 조각을 아무리 빨리 풀어도 합치는 `f(n)`이 크면 전체가 그 비용에 끌려간다. 결합이 `O(n^2)`이면 쪼갠 이득이 사라진다.
   - **개선방안**: 병합에 임시 배열·투 포인터를 써서 결합을 `O(n)` 선형으로 유지하고, 점화식에 결합 비용을 명시해 미리 확인한다. (확인: 단계별 결합 비용 = `O(n)` 이하)

3. **겹치는 부분 문제를 방치**: 조각이 서로 독립이 아니라 같은 하위 문제를 반복해 계산하면(피보나치 재귀 등), 같은 값을 지수 번 다시 구해 시간이 폭발한다.
   - **개선방안**: 겹침이 확인되면 답을 표에 저장해 재사용하는 메모이제이션·DP로 전환한다. (확인: 같은 하위 문제 재계산 횟수 = 0)

## 5. 실무 적용 사례

| 적용 영역 | 어떻게 쓰나 | 무엇으로 효과를 확인하나 |
|:---|:---|:---|
| 대용량 정렬 | 병합 정렬·퀵 정렬로 데이터를 반씩 쪼개 정렬 후 병합 | 처리 시간, 최악 재귀 깊이 |
| 정렬 데이터 검색 | 이진 탐색으로 가운데와 비교해 후보 절반을 매번 버림 | 비교 횟수(`log n`), 응답 지연 |
| 대규모 병렬 처리 | 서로 독립인 조각을 여러 코어·노드에 나눠 동시 실행 후 결과 병합 | 병렬 효율(코어 대비 속도 향상), 결합 비용 |

> 요약: 정렬·검색은 절반씩 버려 `log` 단계로, 병렬 처리는 조각의 독립성을 그대로 코어 분배에 활용한다.

부분 문제가 서로 독립이라는 성질은 병렬 처리에서 특히 값지다. 왼쪽 절반과 오른쪽 절반이 남의 답을 보지 않으니 별도 코어에서 동시에 돌려도 충돌이 없고, 다 끝난 뒤 한 번만 합치면 되기 때문이다.

## 6. 결론

분할 정복은 큰 문제를 겹치지 않는 조각으로 쪼개 단계 수를 `log n`으로 줄이고, 각 단계의 결합만 싸게 처리해 `O(n log n)`급 성능을 얻는 설계 전략이다. 실무의 판단은 세 가지로 좁혀진다. 조각을 반씩 균형 있게 가를 수 있는가, 합치는 비용을 선형 이하로 누를 수 있는가, 그리고 조각이 서로 겹치지는 않는가이다. 특히 마지막 조건이 깨져 같은 하위 문제가 반복되면 분할 정복이 아니라 DP로 옮겨야 한다는 점이 오적용을 막는 핵심이다.
