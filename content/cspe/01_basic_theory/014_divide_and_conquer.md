## 미리 알고가기

- 분할(Divide): 해결하기 어려운 큰 문제를 동일한 성격의 작은 부분 문제들로 쪼개는 과정임
- 정복(Conquer): 더 이상 쪼개지지 않는 가장 작은 단위의 문제(Base Case)를 직접 해결하는 과정임
- 통합(Combine): 정복된 부분 문제들의 해를 결합하여 원래 문제의 최종 해를 도출하는 과정임
- 재귀(Recursion): 분할 정복 알고리즘을 구현하는 핵심적인 프로그래밍 기법임

## Ⅰ. 개요

- **정의/개념**: 분할 정복은 복잡한 문제를 직접 해결하기 쉬운 크기의 독립적인 부분 문제로 반복하여 분할하고, 각 문제의 해를 구한 뒤 이를 다시 결합하여 원본 문제를 해결하는 하향식($Top-down$) 설계 전략임
- **배경/필요성**: 문제의 규모가 커질수록 연산 복잡도가 비선형적으로 증가하는 문제를 해결하기 위해, 문제를 관리 가능한 작은 단위로 나누어 처리 흐름을 단순화하고 병렬 처리 가능성을 확보하기 위해 도입됨

## Ⅱ. 특징

- 하위 문제들이 서로 겹치지 않고 독립적($Independent$)인 경우에 최적의 효율을 발휘하며, 각 부분 문제를 동시에 처리할 수 있어 멀티코어 환경의 병렬화에 유리함
- 동일한 알고리즘을 반복적으로 적용하여 문제를 분해하므로 재귀적 구조가 명확하며, 마스터 정리($Master$ $Theorem$)를 통해 알고리즘의 전체 시간복잡도를 수식화하기 쉬움
- 문제를 쪼개는 비용과 풀린 해를 다시 합치는 결합 비용($Combine$ $Cost$)의 합이 원래 문제를 한 번에 푸는 비용보다 작아야 실질적인 성능 개선 효과를 얻을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 정복 (Divide & Conquer) | 동적 프로그래밍 (DP) |
|:---|:---|:---|
| **부분 문제 관계** | 상호 독립적 (Independent) | 상호 의존적 / 중복 발생 (Overlapping) |
| **처리 방식** | 재귀적 분산 후 최종 결합 | 작은 문제의 답을 저장 후 재사용 |
| **핵심 기법** | 재귀 호출 (Recursion) | 메모이제이션, 타뷸레이션 |
| **성능 병목** | 결합(Combine) 과정의 비용 | 상태 저장(Memory) 공간의 한계 |
| **대표 사례** | 병합 정렬, 퀵 정렬, 이진 탐색 | 최단 경로, 배낭 문제, 피보나치 |

> 요약: 부분 문제가 독립적이면 분할 정복을, 부분 문제가 반복되어 나타나면 동적 프로그래밍을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분할 논리 | 문제를 어떤 기준으로, 몇 개의 부분 문제로 나눌지 결정하는 분기 로직임 |
| 기저 사례 ($Base$ $Case$) | 더 이상 분할할 필요가 없는 가장 작은 문제의 상태이며, 재귀 호출의 탈출 조건임 |
| 결합 연산 | 분할된 영역에서 산출된 부분 해들을 논리적으로 병합하여 상위 문제의 해로 만드는 과정임 |
| 제어 흐름 | 호출 스택을 통해 하향식으로 문제를 전달하고 상향식으로 결과를 집계하는 흐름임 |

```text
[ 분할 정복 처리 흐름 ]
         (원래 문제 P)
         /          \
    (분할 P1)      (분할 P2)
     /    \         /    \
 (S1)    (S2)    (S3)    (S4)  <-- 정복 (Solve)
     \    /         \    /
    (결합 H1)      (결합 H2)
         \          /
         (최종 해 H)           <-- 통합 (Combine)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 기저 조건 확인| --> | 부분 문제 분할 | --> | 재귀적 정복   | --> | 해의 통합    |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **기저 확인** — 입력받은 문제의 규모가 직접 해결 가능한 최소 단위($Base$ $Case$)인지 확인하고, 그렇다면 답을 즉시 반환함
2. **문제 분할** — 문제가 여전히 크다면 이를 동일한 성격의 작은 부분 문제들로 나눔 (예: 배열을 절반으로 나눔)
3. **재귀 정복** — 나뉘어진 각 부분 문제들에 대해 동일한 알고리즘을 재귀적으로 호출하여 부분 해를 구함
4. **해의 통합** — 각 재귀 호출로부터 반환된 부분 해들을 결합 규칙에 따라 하나로 합쳐 상위 레벨의 해를 도출함

## Ⅵ. 실무 적용 및 유의점

1. 부분 문제들이 서로 독립적이지 않고 결과값을 공유해야 하는 상황에서 분할 정복을 적용하면 동일한 계산이 중복 수행되어 성능이 급격히 저하되므로, 문제의 의존성을 분석하여 필요시 동적 프로그래밍으로 전환해야 함
2. 재귀 호출의 깊이가 매우 깊어질 경우 $Stack$ $Overflow$가 발생할 수 있으므로, 분할의 균형($Balance$)을 유지하도록 설계하거나(예: 퀵 정렬의 피벗 선택 최적화), 호출 스택을 반복문으로 대체하여 시스템 안정성을 확보해야 함

## Ⅶ. 결론

- 분할 정복은 거대한 문제를 단순화하여 해결하는 현대 알고리즘 설계의 근간이며, 설계자는 분할의 이득과 결합의 비용을 정밀하게 계산하여 시스템의 처리 효율을 극대화해야 함
