## 미리 알고가기

- **가변 길이 부호화(Variable Length Coding)**: 모든 기호에 동일한 비트를 할당하는 고정 길이 방식과 달리, 출현 빈도에 따라 서로 다른 길의 비트를 할당하는 방식
- **접두사 코드(Prefix Code)**: 어떤 부호도 다른 부호의 앞부분(접두어)이 되지 않도록 설계된 코드. 비트열을 읽을 때 모호성 없이 즉시 복호화가 가능함
- **그리디 알고리즘(Greedy Algorithm)**: 매 단계에서 가장 최적인 선택(여기서는 빈도가 가장 낮은 두 노드 결합)을 통해 전체의 최적해를 구하는 방식

## Ⅰ. 개요

- **정의/개념**: 허프만 코딩(Huffman Coding)은 데이터 내 각 기호의 출현 빈도를 기반으로, 자주 나타나는 기호에는 짧은 코드를, 드물게 나타나는 기호에는 긴 코드를 할당하여 전체 데이터의 평균 비트 길이를 최소화하는 무손실 압축 기법임
- **배경/필요성**: 표준 ASCII처럼 모든 글자를 8비트로 저장하면 구현은 쉽지만, 'e'와 'z'의 출현 확률 차이를 이용하지 못해 저장 공간이 낭비됨. 정보이론에 따르면 이상적인 코드 길이는 $-\log_2 P(x)$에 비례해야 함. 허프만 코딩은 이러한 확률적 특성을 이용해 엔트로피(Entropy) 한계에 근접하는 압축률을 달성하면서도, 접두사 코드 규칙을 통해 가변 길이 코드의 고질적인 문제인 '어디서 끊어 읽을 것인가'의 모호성을 해결함

## Ⅱ. 특징 및 비교

### 가. 주요 부호화 방식 비교

| 구분 | 고정 길이 부호화 (Fixed Length) | 허프만 코딩 (Huffman) | 산술 코딩 (Arithmetic) |
|:---|:---|:---|:---|
| 코드 길이 | 모든 기호가 동일함 | 빈도에 따라 정수 비트 할당 | 전체 메시지를 소수점 구간으로 표현 |
| 압축 성능 | 낮음 (분포 활용 불가) | 우수 (이론적 최적에 근접) | 매우 우수 (기호당 1비트 미만 가능) |
| 구현 복잡도 | 매우 낮음 | 중간 (트리 구성 및 관리) | 높음 (정밀도 연산 및 모델 관리) |
| 복호화 속도 | 매우 빠름 | 빠름 (트리 탐색) | 상대적으로 느림 |
| 특징 | 구조가 단순하고 처리가 용이함 | 정수 비트 제약 하의 최적해 | 마지막 1비트까지 짜내는 극한 압축 |

> 요약: 보편적인 최적 압축 성능과 구현 용이성을 동시에 확보해야 할 때 허프만 코딩이 가장 선호됨

### 나. 허프만 코딩의 주요 성질
- **유일 복호화 가능성**: 접두사 규칙 덕분에 왼쪽에서 오른쪽으로 읽으며 즉시 기호를 식별 가능
- **최적성**: 기호 단위 부호화 방식 중에서 평균 비트 길이가 가장 짧은 코드를 생성함
- **데이터 의존성**: 데이터의 확률 분포가 치우쳐 있을수록 압축 효율이 극대화됨

## Ⅲ. 구성요소/구조

### 가. 허프만 트리 구성 알고리즘

```text
[빈도 집계] -> [우선순위 큐 삽입] -> [최소 노드 추출/결합] -> [트리 완성] -> [부호 할당]

1. 모든 기호와 그 빈도를 노드로 생성하여 우선순위 큐(최소 힙)에 삽입
2. 큐에서 빈도가 가장 낮은 두 노드를 꺼내 부모 노드로 합침 (부모 빈도 = 자식 빈도 합)
3. 합쳐진 부모 노드를 다시 큐에 삽입
4. 노드가 하나 남을 때까지 반복 (이 노드가 루트가 됨)
5. 루트에서 각 리프(기호)까지 경로를 따라 0(왼쪽)과 1(오른쪽)을 부여
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 빈도표 (Freq Table) | 각 기호가 데이터 내에서 나타나는 횟수 기록 | 압축률을 결정하는 기초 데이터 |
| 허프만 트리 | 기호들을 리프 노드로 갖는 이진 트리 | 트리의 깊이가 곧 코드의 길이 |
| 코드 사전 (Dictionary) | 기호와 할당된 비트열의 매핑 정보 | 복호화를 위해 압축 데이터와 함께 전달 |
| 우선순위 큐 (Heap) | 항상 최소 빈도 노드를 보장하는 자료구조 | 트리 구성 시간 복잡도 O(n log n) 결정 |

> 요약: 출현 빈도를 트리 구조의 깊이로 치환하여, 확률이 높은 기호를 루트와 가깝게 배치하는 구조임

## Ⅳ. 문제점 및 개선방안

1. **데이터 분포 변화에 따른 효율 저하**: 파일 내에서 기호 분포가 수시로 변할 경우, 고정된 트리로는 후반부 압축률이 떨어지거나 오히려 커짐
   - **개선방안**: 데이터를 읽으면서 실시간으로 빈도를 갱신하고 트리를 재구성하는 '적응형 허프만(Adaptive Huffman)' 알고리즘을 적용함

2. **사전(Dictionary) 저장 오버헤드**: 작은 파일의 경우 코드 사전을 포함한 전체 크기가 원본보다 커지는 '압축 역전' 현상 발생
   - **개선방안**: 데이터가 일정 크기 미만이면 압축을 생략하거나, 트리 대신 각 코드의 길이 정보만 저장하는 '정준 허프만(Canonical Huffman)'으로 사전 크기를 축소함

3. **비트 오류에 대한 취약성**: 가변 길이 코드 특성상 중간에 1비트만 깨져도 이후의 모든 코드 경계가 무너져 전체 데이터가 오염됨
   - **개선방안**: 일정 간격마다 동기화 마커(Sync Marker)를 삽입하거나, 오류 정정 코드(FEC)를 결합하여 손상 범위를 국소화함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 정적 압축 (ZIP/GZIP) | LZ77로 중복 문자열을 제거한 후 남은 리터럴과 거리를 허프만으로 2차 압축 | 최종 파일 크기, 압축 속도 |
| 이미지 압축 (JPEG) | DCT 변환 및 양자화 후 발생하는 0의 런타임과 유효 계수를 허프만 부호화 | 압축률 대비 화질(PSNR) |
| 네트워크 프로토콜 (HTTP/2) | 헤더의 중복 전송을 막기 위해 HPACK 알고리즘 내에서 정적 허프만 사용 | 헤더 전송 지연, 트래픽 절감량 |

> 요약: 단독 사용보다는 다른 압축 알고리즘의 최종 단계에서 엔트로피 압축을 마무리하는 용도로 널리 쓰임

## Ⅵ. 결론

허프만 코딩은 확률적 불확실성을 물리적 공간 절약으로 치환하는 가장 직관적이고 효율적인 압축 도구임. 기호 단위로 정수 비트를 할당해야 한다는 제약이 있으나, 그만큼 복호화 구조가 명확하고 처리 속도가 빨라 현대 컴퓨팅의 거의 모든 압축 표준에서 필수 요소로 자리 잡음.

기술사는 데이터의 성격(텍스트, 멀티미디어, 로그 등)에 따라 허프만 코딩의 적용 여부와 변형(적응형, 정준형 등)을 선택할 수 있어야 하며, 특히 임베디드나 실시간 통신 환경에서는 사전 저장 오버헤드와 연산 복잡도 사이의 균형을 맞추는 설계 역량이 요구됨.
