## 미리 알고가기

- 가변 길이 부호(Variable-Length Code): 기호별 발생 빈도에 따라 서로 다른 길이의 코드를 쓰는 방식임
- 접두 부호(Prefix Code): 어떤 코드도 다른 코드의 앞부분이 아니어서 구분자 없이 순차 복호하는 코드임
- 엔트로피(Entropy): 평균 정보량이며 무손실 압축률의 이론 하한임
- 최소 힙(Min-Heap): 가장 작은 빈도 노드 두 개를 반복해 꺼내는 우선순위 큐임
- 코드북(Codebook): 기호와 허프만 코드의 대응표임
- 고정 길이 부호(Fixed-Length Code): 모든 기호를 같은 비트 수로 표현하는 부호화 방식임
- 산술 코딩(Arithmetic Coding): 기호열 전체를 누적 확률 구간의 한 값으로 표현하는 무손실 부호화 방식임

## 작성 근거(검토용)

- **개요 구성**: 키워드의 본질이 빈도 기반 가변 길이 부호이므로 정의와 특징을 이 축으로 통일함
- **Ⅱ. 특징 선정**: 접두 부호를 별도 용어로 설명해 구분자 없이 복호되는 이유를 앞에서 정리함
- **Ⅲ. 비교축 선정**: 고정 길이 부호와 산술 코딩을 두어 부호화 메커니즘, 처리 단위, 주요 제약의 차이가 보이게 함
- **Ⅳ·Ⅴ. 구조·절차 선정**: 빈도표·힙·트리·코드북으로 실제 구현 순서를 따라 배치함
- **Ⅵ·Ⅶ. 사례·결론 선정**: 코드북 오버헤드와 분포 변화는 압축 알고리즘 선택을 바꾸는 핵심 조건임
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 접두 부호 정의와 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 허프만 코딩은 접두 부호로 빈도 높은 기호에 짧은 코드를 배정하는 무손실 압축 알고리즘임
- **배경/필요성**: 데이터의 평균 비트 수를 줄이기 위해 빈도 편중을 반영하는 부호화가 필요함

### 쉽게 이해하기 (학습용)
- 자주 쓰는 인사말은 손짓 하나로, 가끔 쓰는 말은 문장으로 표현해 평균 대화 시간을 줄이는 것과 같음

## Ⅱ. 특징

- 주어진 기호 빈도에서 접두 부호의 평균 코드 길이를 최소화함
- 접두 부호 조건으로 구분자 없이 순차 복호함
- 가장 낮은 빈도의 두 노드를 반복 결합하는 탐욕 구조임
- 기호 확률이 $2^{-k}$ 꼴에 가까울수록 평균 코드 길이가 엔트로피에 더 근접함

### 쉽게 이해하기 (학습용)
- 어떤 신호음도 다른 신호음의 앞부분과 겹치지 않아 끊어 듣지 않아도 저절로 구분되며, 매번 가장 작은 두 뭉치만 골라 합쳐가는 방식임
- 기호 비율이 1/2, 1/4처럼 딱 떨어질수록 이 방식이 이론적 최선에 더 가까워짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정 길이 부호 | 허프만 코딩 | 산술 코딩 |
|:---|:---|:---|:---|
| 부호화 메커니즘 | 기호별 고정 폭 매핑 | 빈도 기반 접두 트리 | 누적 확률 구간 분할 |
| 처리 단위 | 개별 기호 | 개별 기호 | 기호열 전체 |
| 주요 제약 | 빈도 편중 미반영 | 코드북 저장 부담 | 고정밀 구간 연산 부담 |

> 요약: 허프만 코딩은 빈도 기반 접두 트리로 평균 코드 길이를 줄임.

### 쉽게 이해하기 (학습용)
- 모든 사람에게 같은 크기의 봉투를 주는 방식(고정 길이), 짐 양에 맞는 봉투를 만드는 방식(허프만), 짐 전체를 하나의 숫자로 뭉뚱그리는 방식(산술 코딩)의 차이임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 빈도표 | 기호별 출현 횟수 |
| 최소 힙 | 빈도가 가장 낮은 두 노드를 선택하기 위한 우선순위 큐 |
| 허프만 트리 | 내부 노드의 결합 빈도·단말 노드의 기호 |
| 코드북 | 기호별 루트-단말 경로 코드 |

> 요약: 허프만 코딩은 최소 힙으로 낮은 빈도 노드를 결합해 빈번한 기호에 짧은 트리 경로를 배정함.

### 쉽게 이해하기 (학습용)
- 방문 횟수를 적은 장부(빈도표), 가장 한산한 두 손님을 먼저 짝짓는 대기줄(최소 힙), 그렇게 완성된 좌석 배치도(트리)와 좌석표(코드북)가 차례로 만들어짐

## Ⅴ. 원리 및 절차 흐름도

```text
기호 빈도 집계 → 최소 힙 구성 → 최저 빈도 노드 2개 결합
                                         ├─ 노드 2개 이상 → 힙에 삽입·반복
                                         └─ 루트 완성 → 경로 코드 생성 → 비트열 치환
```

1. 원본 데이터를 스캔해 기호별 빈도를 계산함
2. 모든 기호를 빈도 기준 최소 힙에 넣음
3. 최저 빈도 노드 두 개를 꺼내 부모 노드로 결합함
4. 루트에서 단말까지의 0/1 경로를 코드북에 기록함
5. 원본 기호를 코드북 비트열로 치환함

> 요약: 최저 빈도 노드를 결합하고 루트-단말 경로를 코드로 정해 원본 기호를 치환함.

### 쉽게 이해하기 (학습용)
- 가장 인기 없는 두 팀을 계속 합쳐 하나의 큰 대진표를 만들고, 완성된 대진표에서 각 팀까지 가는 길을 그 팀의 암호로 정하는 과정과 같음

## Ⅵ. 실무 사례

1. 허프만 압축기는 코드북을 포함한 결과가 원본보다 작을 때만 압축 형식으로 저장함
2. 스트림 압축기는 블록마다 기호 빈도를 다시 집계해 코드 트리를 갱신함

### 쉽게 이해하기 (학습용)
- 포장 재료값(코드북)까지 쳐서 오히려 손해면 포장을 안 하고 원본 그대로 두며, 상자마다 내용물이 바뀌면 포장 설계도도 새로 그리는 것과 같음

## Ⅶ. 결론

- 허프만 코딩은 빈도 기반 가변 길이 부호로 평균 비트 수를 줄이나 코드북 공유가 필요함
- 데이터 분포가 자주 바뀌거나 블록이 작으면 코드북 비용이 이득을 없앨 수 있으므로 원본 저장 전환 임계값을 두어야 함

### 쉽게 이해하기 (학습용)
- 압축하려면 설계도(코드북)를 상대방과 미리 공유해야 하는데, 짐이 작거나 자주 바뀌면 설계도 만드는 수고가 오히려 손해라 그냥 줄이지 않고 보내는 게 나을 때도 있음
