## Ⅰ. 개요

- **정의**: 문자 빈도에 따라 가변 길이 접두어 코드를 생성해 평균 코드 길이를 최소화하는 무손실 압축 알고리즘
- **배경/필요성**: 고정 길이 코드(ASCII 8비트)는 문자 빈도 불균등을 반영하지 못해 대역폭을 낭비하므로, 접두어 코드 성질을 유지하면서 빈도가 낮은 두 노드를 반복 결합해 엔트로피 하한(031 참조)에 근접시키는 구성 절차가 필요함
- **출제 의도**: 그리디 결합 절차(빈도 낮은 두 노드 결합)의 구체 동작과 최적성, 엔트로피 대비 압축 한계를 판단하는 능력 확인
- **답안 방향**: 트리 구축 절차(빈도표→힙→결합) → 접두어 코드 성질 → 엔트로피 대비 근접도·한계 → 산술 코딩·ANS와의 선택 기준으로 전개

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 빈도 기반 최적 접두어 코드 구성 절차 이해 | 최소 힙, 두 노드 결합, 접두어 코드 성질 | 트리 구축 과정 없이 개념만 서술 |
| 엔트로피 대비 한계와 대안 판단 | 정수 비트 제약(최대 1비트/심볼 초과), 산술 코딩·ANS 비교 | "허프만이 항상 최적 압축"이라는 범위 오류 |

> 요약: 빈도 낮은 두 노드를 반복 결합하는 구체 절차와, 정수 비트 제약이 만드는 엔트로피와의 격차를 정확히 짚어야 함.

## Ⅱ. 구조 및 구성요소

```text
문자별 빈도표 -> 최소 힙(우선순위 큐) 구성 -> 최소 두 노드 결합 반복 -> 단일 루트 트리 확정 -> 경로 비트로 코드 테이블 산출
                                                    |
                                                    +-> 결합마다 접두어 성질 보존(심볼은 리프에만 위치)
```

| 구성요소 | 역할 | 비유 |
|:---|:---|:---|
| 빈도표(Frequency Table) | 입력 심볼별 출현 횟수 집계, 트리 구축의 입력값 | 출석부 |
| 최소 힙(Min-Heap) | 매 단계 빈도가 가장 낮은 두 노드를 O(log K)에 추출 | 몸무게 순 줄 세우기 |
| 내부 노드(결합 노드) | 두 자식 빈도의 합을 가짐, 리프가 아니므로 코드 미부여 | 두 조를 합친 상위 조 |
| 리프 노드(심볼 노드) | 실제 문자, 루트-리프 경로가 곧 코드가 됨 | 각자의 최종 자리 |
| 접두어 코드(Prefix-Free Code) | 어떤 코드도 다른 코드의 접두어가 아님, 구분자 없이 유일 디코딩 | 지역 전화번호 체계 |

> 요약: 빈도표를 최소 힙에 넣고 가장 작은 두 노드를 반복 결합해 만든 이진 트리의 루트-리프 경로가 각 심볼의 접두어 코드가 됨.

## Ⅲ. 동작원리 및 흐름도

```text
빈도 계산 -> 최소 힙 삽입 -> [최소 두 노드 추출 -> 결합 후 재삽입] 반복(힙 크기 1까지) -> 경로 비트 할당(좌 0 / 우 1)
```

- 1단계 빈도 계산: 예시 문자열 "ABRACADABRA"(11자)에서 A=5, B=2, R=2, C=1, D=1 집계 후 5개 리프 노드를 힙에 삽입
- 2단계 최소 두 노드 결합(반복): C:1과 D:1을 결합해 CD:2 생성 → B:2와 R:2를 결합해 BR:4 생성 → CD:2와 BR:4를 결합해 결합6 생성 → A:5와 결합6을 결합해 루트(11) 확정. 이 결합 절차는 그리디 알고리즘(015 참조)을 빈도 결합에 특화한 사례이며, 매 단계 최소 두 값을 형제로 묶는 선택이 전역 최적 트리를 만듦이 교환 논증으로 증명됨
- 3단계 코드 부여: 루트에서 왼쪽 간선에 0, 오른쪽 간선에 1을 부여하며 리프까지의 경로를 읽어 A=0, B=110, R=111, C=100, D=101을 확정(빈도가 높을수록 코드 길이가 짧음)
- 4단계 압축 검증: 원본 11×8=88비트를 5×1+2×3+2×3+1×3+1×3=23비트로 줄여 약 74% 절감하며, 이 분포의 엔트로피 ≈22.45비트(031 참조)에 근접함을 확인

```text
루트(11)
 +-- A:5              => 코드 0
 +-- 결합(6)
      +-- 결합(4)
      |     +-- B:2   => 코드 110
      |     +-- R:2   => 코드 111
      +-- 결합(2)
            +-- C:1   => 코드 100
            +-- D:1   => 코드 101
```

> 요약: 최소 두 노드를 반복 결합하는 4단계만으로 원본 대비 약 74% 절감하며 엔트로피 하한에 근접하는 코드가 산출됨.

## Ⅳ. 특징

- 접두어 코드 보장: 모든 심볼이 리프에만 위치하므로 구분자 없이 비트스트림만으로 유일 디코딩이 가능함
- 정수 비트 제약(한계): 심볼 확률이 2의 거듭제곱이 아니면 엔트로피보다 최대 1비트/심볼을 초과 소비함(예: 확률 0.9인 심볼도 이론상 약 0.15비트면 충분하나 최소 1비트가 필요)
- 구현 단순성: 힙 연산과 트리 순회만으로 구성되어 정수 연산만 사용하며, 산술 코딩 대비 하드웨어 구현이 단순함
- 정적/적응적 변형: 정적 허프만은 빈도표를 별도 전송해야 하나, 적응적 허프만은 스트리밍 중 트리를 실시간 갱신해 이 오버헤드를 제거함

## Ⅴ. 심화 비교 및 적용 판단

| 압축 판단 기준 | 허프만 코딩 | 산술 코딩 | ANS(rANS/tANS) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 압축 효율 | 엔트로피 대비 최대 1비트/심볼 초과 | 엔트로피에 사실상 수렴 | 엔트로피에 수렴 | 심볼당 1비트 손실 허용 여부 |
| 구현·연산 복잡도 | 정수 연산만 사용, 낮음 | 구간 분할 실수 연산, 높음 | 정수 연산, 중간 | 임베디드·저전력 환경은 허프만 |
| 처리 속도 | 빠름(트리 순회) | 느림(순차 상태 의존) | 빠름(병렬화 가능) | 실시간 스트리밍은 허프만·ANS |
| 대표 활용 | JPEG, gzip/DEFLATE | JPEG2000, H.265 CABAC | zstd, LZMA2 | 신규 코덱은 ANS로 전환 추세 |

> 요약: 구현 단순성·표준 호환성이 우선이면 허프만을, 압축률이 절대적이면 산술 코딩·ANS를 선택함.

**리스크·대응**:
- 고엔트로피 데이터 재압축: 암호화·기압축 데이터에 허프만 적용 시 트리 오버헤드로 크기 증가 → 압축 전 표본 엔트로피 추정 후 적용 여부 판단 (지표: 압축 후/전 크기비)
- 정수 비트 제약으로 인한 손실: 심볼 확률이 2의 거듭제곱과 어긋날 때 평균 코드 길이가 엔트로피를 초과 → 산술 코딩·ANS 전환 검토 (지표: 실측 평균 코드 길이와 엔트로피의 격차)
- 빈도표 전송 오버헤드: 정적 허프만은 트리·빈도표를 별도 전송해야 함 → 적응적 허프만 또는 HPACK 정적 테이블 같은 표준 테이블 재사용 (지표: 헤더 대비 오버헤드 비율)

**도입 후 점검 지표**:
- 압축률: 원본 대비 압축 후 크기 비율, 목표는 해당 분포 엔트로피의 105% 이내
- 처리량: 인코딩·디코딩 처리 속도(MB/s), 실시간 스트리밍 요구 지연 기준 충족 여부

## Ⅵ. 실무 적용 및 결론

1. 단기: 대상 데이터의 빈도 분포를 분석해 반복도가 낮은 텍스트·헤더 등 허프만 적용 대상을 식별하고 PoC로 압축률을 측정
2. 중기: gzip/DEFLATE, JPEG 등 검증된 파이프라인에 통합하고, 적응적 허프만 도입으로 사전 빈도표 전송 오버헤드를 제거
3. 장기: 압축률이 절대적으로 중요한 신규 영역(zstd 등)은 ANS 기반 코덱으로 전환하고, 허프만은 저복잡도·레거시 호환이 필요한 구간에 유지

- 기술사적 판단: 구현 단순성·표준 호환성이 우선이면 허프만, 압축률이 절대적이면 산술 코딩·ANS를 채택
- 기술사 제언: 신규 엔트로피 코더 설계 시 압축률 수치보다 "심볼 분포가 정수 비트에 얼마나 정합하는가"부터 확인해야 불필요한 전환 비용을 피할 수 있음
- 향후 발전 방향: HPACK·zstd 사례처럼 정적 허프만 테이블을 표준화하거나, 속도가 중요한 영역은 ANS 계열로 대체하는 추세임
