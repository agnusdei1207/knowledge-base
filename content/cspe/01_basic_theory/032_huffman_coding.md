## 미리 알고가기

- 가변 길이 부호($VLC$): 기호의 발생 빈도에 따라 서로 다른 길이의 부호를 할당하는 방식임
- 접두 부호($Prefix$ $Code$): 어떤 부호도 다른 부호의 앞부분(접두사)이 되지 않는 부호로, 별도의 구분자 없이 즉시 복호가 가능함
- 엔트로피($Entropy$): 정보원이 가질 수 있는 평균 정보량으로, 무손실 압축이 가능한 이론적 최소 비트수임
- 최소 힙($Min-Heap$): 가장 작은 빈도값을 가진 노드를 효율적으로 추출하기 위해 사용하는 트리 구조의 자료구조임

## Ⅰ. 개요

- **정의/개념**: 허프만 코딩은 데이터 내 각 기호의 발생 빈도를 기반으로 이진 트리를 구성하여, 자주 나타나는 기호에는 짧은 부호를, 드물게 나타나는 기호에는 긴 부호를 할당하는 최적 무손실 압축 알고리즘임
- **배경/필요성**: 모든 기호에 동일한 비트를 할당하는 고정 길이 부호($ASCII$ 등)는 데이터의 통계적 중복을 제거하지 못하므로, 저장 공간과 전송 대역폭을 효율적으로 사용하기 위한 데이터 압축 기술이 필요함

## Ⅱ. 특징

- 발생 확률이 높은 기호일수록 트리의 루트에 가깝게 배치하여 전체 메시지의 평균 코드 길이를 엔트로피 한계치에 근접하게 최소화함
- 생성된 부호가 접두사 조건을 만족하므로 수신 측에서 비트 스트림을 읽는 즉시 모호성 없이 원래의 기호로 복원할 수 있는 순시 복호($Instantaneous$ $Decoding$)가 가능함
- 그리디 알고리즘($Greedy$ $Algorithm$)의 일종으로, 매 단계에서 가장 빈도가 낮은 두 노드를 결합하는 단순한 절차를 통해 수학적으로 최적의 가변 길이 부호를 생성함

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정 길이 부호 | 허프만 코딩 | 산술 코딩 (Arithmetic) |
|:---|:---|:---|:---|
| **부호 길이** | 일정함 (예: 8비트) | 기호별 가변 (정수 비트) | 기호별 가변 (소수 비트) |
| **압축 효율** | 없음 | 높음 (엔트로피 근접) | 매우 높음 (엔트로피 일치) |
| **복호 속도** | 매우 빠름 | 빠름 | 상대적으로 느림 (복잡) |
| **구현 난이도** | 매우 쉬움 | 쉬움 (트리 기반) | 어려움 (구간 연산) |
| **주요 활용** | $ASCII$, $Unicode$ | $JPEG, ZIP, MP3$ | $H.264, JBIG2$ |

> 요약: 허프만 코딩은 속도와 효율성 사이의 균형이 뛰어나 범용 압축 기술의 표준으로 널리 사용됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 빈도표 ($Frequency$) | 각 기호가 전체 데이터에서 출현하는 횟수 또는 확률을 정리한 데이터셋임 |
| 단말 노드 ($Leaf$) | 트리의 가장 끝단에 위치하며, 실제 기호 데이터와 해당 빈도값을 저장함 |
| 내부 노드 ($Internal$) | 두 자식 노드의 빈도 합을 저장하는 매개체로, 경로에 따라 0 또는 1을 할당받음 |
| 허프만 트리 | 루트에서 단말 노드까지의 경로가 곧 해당 기호의 이진 부호가 되는 이진 트리 구조임 |

```text
[ 허프만 트리 구성 예시 ]
       (Root: 1.0)
       /        \
    (0.4:A)    (0.6)
               /    \
            (0.25:B) (0.35:C)
=> A: 0, B: 10, C: 11
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 출현 빈도 계산| --> | 최소 빈도 결합| --> | 이진 트리 완성| --> | 이진 부호 할당|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **빈도 집계** — 원본 데이터를 스캔하여 각 기호별 출현 빈도를 조사하고, 이를 최소 힙에 삽입함
2. **트리 구축** — 힙에서 빈도가 가장 낮은 두 노드를 꺼내 합산 빈도를 가진 부모 노드를 생성하고 다시 힙에 넣는 과정을 노드가 하나 남을 때까지 반복함
3. **코드 생성** — 완성된 트리의 루트에서 각 기호(단말 노드)까지 내려가며 왼쪽 가지에는 0, 오른쪽 가지에는 1을 부여하여 부호표($Codebook$)를 작성함
4. **인코딩** — 원본 기호를 작성된 부호표에 따라 비트열로 치환하여 압축된 데이터를 생성함

## Ⅵ. 실무 적용 및 유의점

1. 데이터의 통계적 특성이 실시간으로 변하는 스트리밍 환경에서는 고정된 허프만 트리 사용 시 압축 효율이 급격히 저하되므로, 데이터 유입에 따라 트리를 동적으로 갱신하는 '적응형 허프만 코딩($Adaptive$ $Huffman$)' 기법을 적용해야 함
2. 압축된 데이터 복호를 위해 송신 측에서 구성한 허프만 트리 정보(또는 빈도표)를 헤더에 포함시켜야 하므로, 데이터 크기가 작을 경우 배포되는 트리 정보의 오버헤드가 실제 압축 이득보다 커질 수 있음을 유의해야 함

## Ⅶ. 결론

- 허프만 코딩은 데이터의 통계적 중복을 최소화하는 무손실 압축의 핵심 알고리즘이며, 설계자는 데이터의 발생 분포와 복호 성능 요구사항을 분석하여 시스템에 최적화된 부호화 전략을 수립해야 함
