## 미리 알고가기

- 무손실 압축: 복원 후 원본 데이터와 완전히 같은 결과를 얻는 압축 방식임
- 가변 길이 코드: 심볼마다 서로 다른 길이의 비트열을 배정하는 코드임
- 접두사 코드: 어떤 코드워드도 다른 코드워드의 앞부분이 되지 않아 즉시 디코딩이 가능한 코드임
- 빈도/확률: 심볼이 나타나는 비율이며 코드 길이 배정의 기준이 됨
- 이진 트리: 왼쪽/오른쪽 간선을 0/1로 해석해 코드워드를 만드는 구조임

## Ⅰ. 개요

- **정의**: 허프만 코딩은 심볼 출현 빈도를 기준으로 가변 길이 접두사 코드를 배정하는 무손실 압축 알고리즘이며, 자주 나오는 심볼에는 짧은 코드, 드문 심볼에는 긴 코드를 배정해 평균 코드 길이를 줄이기 위해 사용함.
- **배경/필요성**: 고정 길이 코드는 모든 심볼에 같은 비트 수를 쓰므로 확률 분포가 치우친 데이터에서 낭비가 크며, 엔트로피에 가까운 압축을 구현할 실용적 방법이 필요함.
- **비유**: 자주 쓰는 단어에는 짧은 약어를 주고 드문 단어에는 긴 이름을 그대로 쓰는 약어 사전과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 허프만 트리 생성 과정 설명 | 낮은 빈도 병합, 이진 트리, 접두사 코드 | 단순 빈도 정렬로만 설명 |
| 압축 특성 판단 | 무손실, 가변 길이, 평균 코드 길이 | 산술 코딩·RLE와 원리 혼동 |

> 요약: 허프만 코딩은 빈도 기반 이진 트리로 접두사 코드를 만들어 평균 비트 수를 줄이는 대표 무손실 압축 기법임.

## Ⅱ. 특징/비교

| 판단 기준 | 고정 길이 코드 | 허프만 코드 |
|:---|:---|:---|
| 코드 길이 | 모든 심볼이 같은 길이를 가짐 | 빈도가 높을수록 짧은 코드를 가짐 |
| 압축 효과 | 심볼 분포가 치우쳐도 비트 절감이 없음 | 확률 분포가 치우칠수록 평균 코드 길이가 감소함 |
| 디코딩 방식 | 일정 비트 단위로 자르면 됨 | 접두사 트리를 따라가며 심볼 경계를 찾음 |
| 선택 기준 | 균등 분포나 단순 인덱싱에 적합함 | 통계적 중복 제거가 중요한 무손실 압축에 적합함 |

- **최적 기준**: 심볼별 독립 코딩과 정수 비트 길이 조건에서는 최적 접두사 코드임.
- **한계 기준**: 확률이 매우 미세한 구간에서는 산술 코딩이 허프만보다 엔트로피에 더 가까울 수 있음.
- **운영 기준**: 압축 데이터와 함께 코드북 또는 canonical 코드 규칙을 전달해야 복원이 가능함.

> 요약: 허프만 코딩은 정수 길이 접두사 코드 조건에서 강력하지만, 코드북 관리와 분포 변화 대응이 필요함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Frequency  | ---> | Priority   | ---> | Huffman    |
| Table      |      | Queue      |      | Tree       |
+------------+      +------------+      +------------+
       |                   |                   |
       v                   v                   v
+------------+      +------------+      +------------+
| Symbols    |      | Merge Low  |      | Prefix     |
| and Prob   |      | Weights    |      | Codes      |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 심볼 집합 | 압축 대상이 되는 문자, 바이트, 토큰 등의 기본 단위임 | 사전의 단어 목록 |
| 빈도표 | 각 심볼의 출현 횟수나 확률을 저장해 코드 길이 배정의 기준이 됨 | 사용 빈도 조사표 |
| 우선순위 큐 | 가장 낮은 빈도의 노드 두 개를 반복 선택하는 자료구조임 | 가장 가벼운 짐 고르기 |
| 허프만 트리 | 낮은 빈도 노드를 상향 병합해 만든 이진 트리임 | 토너먼트 대진표 |
| 접두사 코드 | 루트에서 잎까지의 0/1 경로로 만들어지는 유일 디코딩 코드임 | 겹치지 않는 전화번호 |

> 요약: 허프만 코딩은 빈도표와 우선순위 큐로 트리를 만들고, 루트-잎 경로를 접두사 코드로 해석하는 구조임.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Count      | ---> | Merge      | ---> | Assign     | ---> | Encode     |
| Frequency  |      | Nodes      |      | 0/1 Codes  |      | Stream     |
+------------+      +------------+      +------------+      +------------+
```

1. **빈도 산출**: 입력 데이터의 심볼별 출현 횟수 또는 확률을 계산함.
2. **트리 구축**: 가장 낮은 빈도 노드 두 개를 반복 병합해 하나의 루트 노드를 만듦.
3. **코드 배정**: 왼쪽/오른쪽 간선에 0/1을 부여하고 각 잎 노드까지의 경로를 코드로 정함.
4. **인코딩·검증**: 원본 심볼을 코드로 치환하고 코드북으로 복원 가능성과 평균 코드 길이를 확인함.

> 요약: 허프만 코딩은 빈도를 세고 낮은 빈도부터 병합한 뒤 트리 경로를 코드로 삼아 데이터를 압축함.

## Ⅴ. 문제점

- **P1 코드북 오버헤드**: 압축 데이터와 함께 코드 정보를 저장해야 하므로 작은 파일에서는 압축 이득이 줄어듦.
- **P2 분포 변화 취약성**: 사전에 계산한 빈도와 실제 데이터 분포가 달라지면 평균 코드 길이가 최적에서 멀어짐.
- **P3 비트 단위 처리 비용**: 가변 길이 코드는 심볼 경계가 고정되지 않아 병렬 처리와 임의 접근이 어렵다.

> 요약: 허프만 코딩은 코드북 비용, 분포 불일치, 가변 길이 처리 비용을 관리해야 실효 압축률을 확보할 수 있음.

## Ⅵ. 개선방안

- **P1 대응**: canonical Huffman 코드로 코드북 표현을 줄이고 작은 블록에는 고정 코드 또는 비압축을 선택함. (확인: header overhead)
- **P2 대응**: 블록 단위 빈도 재계산이나 adaptive Huffman으로 데이터 구간별 분포 변화에 대응함. (확인: 평균 코드 길이)
- **P3 대응**: 테이블 기반 디코딩, 블록 분할, SIMD 친화 포맷으로 가변 길이 처리 비용을 낮춤. (확인: decode throughput)

> 요약: 허프만 코딩은 canonical 표현, 블록 적응, 디코딩 테이블 최적화로 압축률과 처리 성능을 균형화해야 함.

## Ⅶ. 전망

- **향후 발전 방향**: DEFLATE, JPEG, PNG 같은 포맷에서 허프만 계열은 계속 쓰이며, 고성능 구현은 하드웨어와 SIMD 최적화로 발전할 전망임.
- **기술사적 판단**: 분포가 치우친 무손실 압축에는 허프만이 실용적이고, 더 높은 압축률이 필요하면 산술 코딩이나 ANS를 검토해야 함.
- **기술사 제언**: 답안에서는 빈도 기반 트리 생성, 접두사 코드, RLE·산술 코딩과의 선택 기준을 함께 제시해야 함.

답안 정리:
- **핵심 키워드**: 빈도표, 우선순위 큐, 허프만 트리, 접두사 코드, 코드북임.
- **연계 키워드**: 정보이론, RLE, DEFLATE 압축으로 연결함.
- **검증 관점**: 어떤 코드도 다른 코드의 접두사가 아닌지 확인함.
