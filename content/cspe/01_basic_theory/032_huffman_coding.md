## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 기호의 발생 빈도에 따라 가변 길이 코드를 할당하여 데이터를 무손실 압축하는 엔트로피 코딩 기법임 |
| 배경/필요성 | 파일 저장 및 네트워크 전송 시 데이터 크기를 최소화하여 스토리지와 대역폭 비용을 절감하기 위해 필요함 |
| 출제 의도 | 접두어 코드(Prefix Code)의 특징과 허프만 트리를 생성하는 탐욕 알고리즘(Greedy)의 이해 평가 |

## Ⅱ. 구성요소
```text
+-------------------+       +-------------------+       +-------------------+
|  Frequency Table  | ----> |   Huffman Tree    | ----> | Variable-Length   |
|  (Symbol counts)  |       |   (Min-heap)      |       | Prefix Codes      |
+-------------------+       +-------------------+       +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 빈도수 테이블 | 각 문자나 기호가 나타나는 횟수를 기록한 표 | 단어장 출현 빈도 |
| 허프만 트리 | 빈도수가 낮은 기호부터 묶어 올라가며 구성된 이진 트리 | 토너먼트 대진표 |
| 가변 길이 접두어 코드 | 트리의 경로(좌 0, 우 1)에 따라 할당된, 서로 겹치지 않는 비트열 | 모스 부호 (짧고 김) |
> 요약: 발생 빈도를 기반으로 이진 트리를 구축하여, 자주 나오는 문자는 짧게, 드문 문자는 길게 코딩함

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 빈도수 집계 | -> | 2. 노드 정렬   | -> | 3. 트리 구축   | -> | 4. 코드 할당   |
+----------------+    +----------------+    +----------------+    +----------------+
```
1. 빈도수 집계: 입력 데이터 전체를 스캔하여 각 기호의 발생 빈도를 계산하고 단말 노드로 생성함
2. 노드 정렬: 우선순위 큐(Min-heap)를 이용하여 노드들을 빈도수 기준 오름차순으로 정렬함
3. 트리 구축: 가장 빈도수가 작은 두 노드를 꺼내 합쳐 새로운 부모 노드를 만들고 다시 큐에 넣는 과정을 트리가 하나 남을 때까지 반복함
4. 코드 할당: 완성된 트리의 루트에서 단말 노드까지 이동하며 왼쪽 간선에는 0, 오른쪽 간선에는 1을 부여해 접두어 코드를 완성함
> 요약: 빈도수가 적은 노드부터 상향식으로 병합하여 트리를 만들고, 경로에 따라 비트를 할당해 압축함

## Ⅳ. 문제점
- 사전 스캔 오버헤드: 코드를 생성하기 위해 데이터 전체를 미리 한 번 읽어야 하므로, 실시간 스트리밍 압축에 불리함
- 트리 정보 전송: 압축 해제를 위해 압축된 데이터와 함께 허프만 트리 구조(메타데이터)를 전송해야 하므로 작은 파일에선 오히려 용량이 커질 수 있음

## Ⅴ. 개선방안
- 적응형 허프만 코딩: 데이터를 읽으면서 실시간으로 트리를 갱신하는 동적(Adaptive) 방식을 적용하여 사전 스캔 문제를 해결함
- 정적/사전 정의 트리 사용: JPEG이나 팩스 전송처럼 도메인이 정해진 경우, 표준화된 허프만 테이블을 미리 공유하여 트리 전송 오버헤드를 없앰

## Ⅵ. 전망
- 허프만 코딩은 그 자체로도 훌륭하지만, LZW나 LZ77 등의 사전 기반 압축 이후 최종 비트 스트림을 줄이는 하이브리드 압축(예: DEFLATE, ZIP)의 핵심 모듈로 계속 활용됨
