## Ⅰ. 개요
- 정의: 데이터 문자의 출현 빈도에 따라 가변 길이 부호를 할당하는 무손실 압축 기법임
- 배경/필요성: 빈도가 높은 문자에 짧은 부호를 부여하여 전체 데이터 크기를 줄임
- 출제 의도: 허프만 트리 구축 과정 및 접두사 코드(Prefix Code) 특성 이해

## Ⅱ. 구성요소
- ASCII 구조도 (Huffman Tree)
        [Root]
       / (0)  \ (1)
    [A:5]    [Node]
            / (0)  \ (1)
         [B:2]    [C:1]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 빈도수 (Freq) | 각 문자가 데이터 내에서 발생하는 횟수 | 인기도 |
| 그리디 알고리즘 | 가장 빈도가 낮은 두 노드를 결합하는 전략 | 짠돌이 전략 |
| 가변 길이 부호 | 문자마다 비트 길이가 다른 코드 | 키차이 배분 |
| 접두사 특성 | 어떤 코드도 다른 코드의 시작부분이 아님 | 이름 중복 방지 |
> 요약: 출현 빈도에 기반하여 최적의 이진 트리를 구성하는 효율적 인코딩 방식임

## Ⅲ. 절차
- ASCII 흐름도
  [Frequency Count] -> [Priority Queue] -> [Build Tree] -> [Assign Codes]

1. 빈도 분석: 대상 데이터에서 각 기호의 출현 빈도를 계산함
2. 최소 노드 결합: 가장 빈도가 낮은 두 노드를 선택해 부모 노드(합산 빈도)를 만듦
3. 트리 완성: 모든 노드가 하나의 루트 아래 연결될 때까지 반복함
4. 부호 할당: 루트에서 잎 노드까지 왼쪽은 0, 오른쪽은 1을 부여하여 경로를 기록함
> 요약: 하향식(Top-down)이 아닌 상향식(Bottom-up)으로 최적 코드를 생성함

## Ⅳ. 문제점
- 고정 트리 한계: 데이터 분포가 실시간으로 변할 경우 효율이 급감함
- 테이블 전송: 디코딩을 위해 트리 구조나 코드 표를 함께 전송해야 하는 부담 존재함

## Ⅴ. 개선방안
- 적응형 허프만: 데이터를 읽으면서 실시간으로 트리를 갱신하여 효율 최적화함
- 산술 코딩: 문자를 구간으로 나누어 표현하여 허프만보다 더 높은 압축률 제공함

## Ⅵ. 전망
- 대규모 로그 최적화: 클라우드 네이티브 환경에서 발생하는 방대한 텍스트 로그의 실시간 압축 및 검색 가속을 위해, 적응형 허프만 코딩 기반의 무손실 압축 엔진 활용이 증가함
- 딥러닝 모델 경량화: 모바일 엣지 디바이스에서의 AI 추론을 위해 가중치(Weight) 분포에 따른 허프만 코딩을 적용하여, 모델 성능 저하 없는 가중치 압축 로드맵의 필수 단계임
- CSF: 데이터 스트림의 동적 특성을 반영한 트리 갱신 오버헤드 관리와 압축률/속도 간의 트레이드오프(Trade-off)를 최적화하는 전략이 성공 요인임
