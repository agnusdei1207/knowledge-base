## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 허프만 코딩(Huffman Coding)은 문자 빈도에 따라 **가변 길이 코드(Variable-Length Code)**를 생성하는 무손실 압축 알고리즘이다. 빈도가 높은 문자에 짧은 코드, 낮은 문자에 긴 코드를 부여하여 평균 코드 길이를 최소화한다. **접두어 코드(Prefix-Free Code)** 중 최적임이 증명되어 있다.
> 2. **가치**: 소스 코딩 정리(엔트로피 = 압축 하한)에 근접하는 실용적 알고리즘으로, gzip, JPEG, MP3, DEFLATE 등 주요 압축 포맷의 핵심 구성 요소이다.
> 3. **융합**: 파일 압축(zip, gzip), 이미지(JPEG의 AC/DC 계수 압축), 네트워크(HTTP/2 헤더 압축=HPACK), 데이터베이스(컬럼 압축), 통신(HDLC 프레임) 등 데이터 전송·저장 전반에 적용된다.

---

### 🔑 핵심 용어 정리

| 용어 | 뜻 | 비유 |
|:---|:---|:---|
| **가변 길이 코드(Variable-Length)** | 심볼마다 다른 길이의 코드를 부여하는 방식. 빈도 높은 심볼에 짧은 코드 | "자주 쓰는 말 줄여쓰기" |
| **접두어 코드(Prefix-Free)** | 어떤 코드도 다른 코드의 접두어가 아닌 코드. 구분자 없이 유일 디코딩 가능 | "전화번호 체계" |
| **산술 코딩(Arithmetic Coding)** | 메시지 전체를 하나의 실수 구간으로 매핑하여 엔트로피에 수렴하는 압축 | "정밀 소수점 계산" |
| **ANS(Asymmetric Numeral Systems)** | 산술 코딩의 속도 문제를 해결한 현대적 엔트로피 코더. zstd, LZMA2에 사용 | "빠른 정밀 압축" |

---

## Ⅰ. 개요 및 필요성

- **개념**: 허프만 알고리즘은 (1) 모든 문자를 빈도 기준 최소 힙에 삽입하고, (2) 빈도가 가장 낮은 두 노드를 꺼내 합쳐 새 부모 노드를 만들며, (3) 힙에 하나의 노드(루트)만 남을 때까지 반복하여 이진 트리를 구축한다. 왼쪽 간선에 0, 오른쪽에 1을 부여하면 각 문자의 코드가 된다.

- **필요성**: ASCII는 모든 문자에 8비트를 균등하게 부여한다. 그러나 영어에서 'e'는 12.7%, 'z'는 0.07% 빈도이므로, 'e'에 짧은 코드를 주면 전체 크기가 줄어든다. 허프만 코딩은 이 불균등을 최대한 활용한다.

- **비유**: 허프만 코딩은 **모스 부호**의 원리와 같다. 가장 자주 쓰는 'E'에 점 하나(·), 드문 'Q'에 점선 4개(− − · −)를 부여한 것이 바로 빈도 기반 가변 길이 코딩이다.

```text
+-----------------------------------------------------------------------+
|        허프만 트리 구축 예시: "ABRACADABRA"                           |
+-----------------------------------------------------------------------+
|                                                                       |
|  [Step 1] 빈도 계산                                                   |
|  A:5, B:2, R:2, C:1, D:1 → 총 11문자                                |
|                                                                       |
|  [Step 2] 최소 빈도 두 개씩 합치기                                   |
|                                                                       |
|  (C:1)(D:1) → [CD:2]                                                |
|  (B:2)(R:2) → [BR:4]                                                |
|  [CD:2] 과 어떤 것? → [CD:2]([BR:4]) 등 ...                        |
|                                                                       |
|  [최종 허프만 트리]                                                   |
|           (11)                                                        |
|          /    \                                                       |
|       (A:5)  (6)                                                     |
|       "0"   /    \                                                   |
|          (BR:4) (CD:2)                                               |
|          / \     / \                                                  |
|       (B:2)(R:2)(C:1)(D:1)                                           |
|       "10" "11" "110" "111"                                          |
|                                                                       |
|  [결과 코드]                                                          |
|  A=0, B=10, R=11, C=110, D=111                                      |
|                                                                       |
|  원본: 11×8 = 88비트 (ASCII)                                        |
|  허프만: 5×1 + 2×2 + 2×2 + 1×3 + 1×3 = 19비트                     |
|  압축률: 88→19, 약 78% 절감                                         |
+-----------------------------------------------------------------------+
```

**[다이어그램 해설]** "ABRACADABRA"에서 A(5회)가 가장 빈번하므로 1비트(0)를 받고, C(1회), D(1회)는 3비트(110, 111)를 받는다. 접두어 코드이므로 어떤 코드도 다른 코드의 접두어가 아니어서, 구분자 없이 연속 비트스트림으로 전송해도 유일하게 디코딩된다. 평균 코드 길이 19/11 ≈ 1.73비트/문자이며, 이 분포의 엔트로피 H ≈ 2.04비트/문자에 근접한다.

- **📢 섹션 요약 비유**: 허프만 코딩은 "자주 쓰는 단어는 약자로, 드문 단어는 풀네임으로" 쓰는 것입니다. "대한민국"을 매번 쓰면 길지만 "한"으로 줄이면 짧아져요.

## Ⅱ. 아키텍처 및 핵심 원리

### 구성 요소

| 요소명 | 역할 | 시간 복잡도 | 관련 기술 | 비유 |
|:---|:---|:---|:---|:---|
| **빈도 분석** | 문자별 출현 횟수 계산 | O(N) | 히스토그램 | 출석부 |
| **최소 힙** | 빈도가 낮은 노드 우선 추출 | 삽입/삭제 O(log K) | 우선순위 큐 | 작은 순 줄 세우기 |
| **트리 구축** | 코드 부여 구조 생성 | O(K log K), K=문자 종류 | 탐욕 알고리즘 | 가계도 만들기 |
| **접두어 코드** | 유일 디코딩 보장 | — | 트리 경로 = 코드 | 전화번호 체계 |

### 허프만 코딩의 한계와 대안

- **한계**: 각 심볼에 정수 비트를 할당하므로, 심볼 확률이 2의 거듭제곱이 아니면 엔트로피보다 최대 1비트/심볼 더 사용한다.
- **대안**: 산술 코딩(Arithmetic Coding)은 메시지 전체를 하나의 실수 구간으로 매핑하여 엔트로피에 사실상 도달한다. ANS(Asymmetric Numeral Systems)는 산술 코딩의 속도 문제를 해결한 현대적 대안이다(zstd, LZMA2에 사용).

- **📢 섹션 요약 비유**: 허프만은 "동전으로 거스름돈 주기"(정수 단위), 산술 코딩은 "정확한 소수점까지 계산"(더 정밀)입니다.

## Ⅲ. 비교 및 연결

### 비교 1: 허프만 vs 산술 코딩 vs ANS

| 비교 항목 | 허프만 | 산술 코딩 | ANS (rANS/tANS) |
|:---|:---|:---|:---|
| **압축 효율** | 엔트로피 + 최대 1비트/심볼 | 엔트로피에 수렴 | 엔트로피에 수렴 |
| **구현 복잡도** | 낮음 | 높음 (정밀 연산) | 중간 |
| **속도** | 빠름 | 느림 | 빠름 |
| **특허** | 없음 | 일부 (만료됨) | 없음 |
| **대표 사용** | JPEG, gzip | JPEG2000, H.265 | zstd, LZMA2 |

### 과목 융합 관점
- **이미지**: JPEG는 DCT 변환 후 양자화된 계수를 허프만 코딩으로 압축한다.
- **네트워크**: HTTP/2의 HPACK 헤더 압축은 정적 허프만 테이블을 사용한다.
- **탐욕 알고리즘**: 허프만 코딩은 탐욕 알고리즘의 대표적 성공 사례이다 — 매 단계에서 빈도가 가장 낮은 두 노드를 합치는 지역 최적 선택이 전역 최적을 보장한다.

- **📢 섹션 요약 비유**: 허프만은 "가성비 좋은 대중차", 산술 코딩은 "최고 연비 하이브리드"(비싸지만 효율↑), ANS는 "전기차"(효율↑+속도↑)입니다.

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오

1. **시나리오 — gzip/DEFLATE 압축**: 웹 서버가 HTML/CSS/JS를 gzip으로 압축하면 전송량이 60~80% 감소한다. DEFLATE = LZ77(사전 매칭) + 허프만 코딩(엔트로피 코딩)의 2단 구조이다.

2. **시나리오 — 적응적(Adaptive) 허프만**: 스트리밍 데이터에서 사전 빈도를 모를 때, 데이터를 읽으면서 실시간으로 허프만 트리를 갱신하는 적응적 허프만을 사용한다.

### 안티패턴
- **이미 고엔트로피 데이터에 허프만 적용**: 암호화된 데이터나 이미 압축된 데이터는 엔트로피가 최대에 가까워 허프만으로 더 줄일 수 없다. 오히려 트리 오버헤드로 크기가 증가할 수 있다.

- **📢 섹션 요약 비유**: 이미 압축된 파일을 다시 압축하면 "이미 짜낸 수건을 다시 짜는 것"과 같습니다. 물(중복)이 없으니 아무리 짜도 안 나옵니다.

## Ⅴ. 기대효과 및 결론

### 정량/정성 기대효과

| 구분 | 고정 길이 (ASCII) | 허프만 코딩 | 개선 효과 |
|:---|:---|:---|:---|
| **정량** | 8비트/문자 | 평균 ~4비트/문자 (영어) | **50%** 절감 |
| **정량** | HTML 원본 100KB | gzip 후 25KB | **75%** 전송량 절감 |
| **정성** | 대역폭 낭비 | 엔트로피에 근접한 압축 | 비용 절감 |

### 참고 표준
- **Huffman, D.A. (1952)**: "A Method for the Construction of Minimum-Redundancy Codes" — 원논문
- **RFC 1951**: DEFLATE 압축 표준 (LZ77 + 허프만)

허프만 코딩은 "빈도가 다른 심볼에 최적 길이를 부여하는" 탐욕 알고리즘의 승리이다. 70년이 넘은 알고리즘이지만 gzip, JPEG, HTTP/2 등 현대 시스템의 핵심 구성요소로 여전히 활발히 사용된다.
