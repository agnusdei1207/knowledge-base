## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 심볼 출현 빈도에 따라 가변 길이 코드를 할당하는 무손실 압축 알고리즘으로, 빈도 높은 심볼에 짧은 코드를 부여함 |
| **배경/필요성** | 고정 길이 코드(ASCII)는 빈도를 반영하지 않아 비효율적이며, 엔트로피에 가까운 압축이 필요함 |
| **출제 의도** | 허프만 트리 구축 과정과 최적 접두사 코드의 성질을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 빈도분석  | --> | 허프만   | --> | 코드할당  |
|          |     | 트리구축  |     | (가변길이)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 빈도 분석 | 각 심볼의 출현 빈도(확률)를 산출함 | 글자 빈도 조사 |
| 허프만 트리 | 빈도가 낮은 심볼부터 병합하여 이진 트리를 상향 구축함 | 토너먼트 대진표 |
| 접두사 코드 | 어떤 코드도 다른 코드의 접두사가 되지 않아 디코딩이 유일함 | 전화번호 체계 |

> 요약: 빈도 분석 → 트리 구축 → 접두사 코드 할당으로 평균 코드 길이를 최소화함.

## Ⅲ. 절차
```
+------------+     +------------+
| 빈도계산   | --> | 최소2개   |
| (심볼별)   |     | 병합       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 코드테이블  | <-- | 트리완성  |
| 생성       |     | (루트도달)|
+------------+     +------------+
```

1. 빈도 계산: 입력 데이터의 각 심볼 출현 빈도를 집계함
2. 최소 2개 병합: 우선순위 큐에서 빈도가 가장 낮은 2개 노드를 꺼내 합산하여 부모 노드를 생성함
3. 트리 완성: 노드가 1개(루트)가 될 때까지 2단계를 반복함
4. 코드 테이블 생성: 루트에서 좌(0)·우(1)로 내려가며 각 리프(심볼)의 코드를 할당함

> 요약: 빈도 → 최소 병합 → 트리 완성 → 코드 할당으로 허프만 코드를 생성함.

## Ⅳ. 문제점
- 정수 비트 제약: 각 심볼 코드가 정수 비트이므로 엔트로피에 정확히 도달하지 못함
- 빈도 사전 필요: 코드 테이블을 디코더에 전달해야 하며, 이 오버헤드가 짧은 데이터에서 큼
- 적응성 부족: 정적 허프만은 데이터 특성 변화에 대응하지 못함

## Ⅴ. 개선방안
- (단기) 적응적 허프만: 데이터를 읽으며 동적으로 트리를 갱신하여 사전 전달을 제거함
- (중기) 산술 코딩: 심볼 확률을 구간으로 매핑하여 정수 비트 제약을 넘어 엔트로피에 근접함
- (장기) ANS(Asymmetric Numeral Systems): Zstd에 채택된 산술 코딩 대안으로 속도와 압축률을 동시 확보함

## Ⅵ. 전망
- DEFLATE(ZIP·gzip)에서 허프만 코딩이 핵심이며, Zstd·Brotli 등 차세대 압축 포맷에서 ANS와 허프만의 하이브리드가 표준이 될 전망임
