# 📖 【암기용】 개념 완전 이해

> 목적: 허프만 코딩을 처음 보는 사람도 접두 부호와 평균 코드 길이 절감 원리를 이해하게 만든다.

## 한눈에
- **개요**: 빈도가 높은 심볼에는 짧은 코드, 낮은 심볼에는 긴 코드를 배정하는 무손실 압축 기법
- **왜 필요한가**: 고정 길이 코드는 모든 문자를 같은 비트로 표현해 빈도 편향을 활용하지 못함
- **핵심 직관**: 자주 쓰는 단어를 약어로 적고, 드문 단어만 길게 적어 전체 문서 길이를 줄이는 방식임

## 깊이 이해
- **배경·문제의식**: ASCII처럼 8bit 고정 길이를 쓰면 `A`가 50%, `D`가 5%인 데이터에서도 같은 비트를 소비함. 압축은 빈도 차이를 코드 길이 차이로 바꾸는 문제임.
- **작동 원리**: 가장 빈도가 낮은 두 심볼을 반복 결합해 이진 트리를 만들고, 왼쪽/오른쪽 간선에 0/1을 붙임. 어떤 코드도 다른 코드의 접두어가 아니므로 구분자 없이 복호 가능함.
- **비유**: 많이 찾는 물건은 입구 가까운 선반, 드문 물건은 안쪽 선반에 배치해 평균 이동 거리를 줄이는 방식임.
- **구체 예시**: 빈도 A:45, B:13, C:12, D:16, E:9, F:5이면 A는 1~2bit 수준, F는 4bit 수준 코드가 배정되어 평균 길이가 8bit 고정 대비 약 2~3bit대로 감소함.
- **흔한 오해·주의점**: 허프만 코딩은 무손실 압축이며 암호화가 아님. 빈도표 또는 트리 정보가 없으면 복호할 수 없음.

## 연결 개념
- 엔트로피 — 평균 코드 길이의 이론적 하한
- 접두 부호 — 구분자 없는 즉시 복호 조건
- 산술 코딩 — 허프만보다 엔트로피에 더 근접 가능한 압축

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 허프만 코딩 답안 양식이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 허프만 코딩은 심볼 빈도 기반 이진 트리로 접두 부호를 생성하는 무손실 소스 코딩임.
> 2. **가치**: 고정 길이 N비트 표현을 평균 코드 길이 `L=Σp_i l_i`로 낮춰 저장·전송 비트 수를 절감함.
> 3. **판단 포인트**: 압축률은 심볼 분포 편향, 트리 저장 오버헤드, 블록 크기에 의해 결정됨.

## Ⅰ. 개요 및 필요성

허프만 코딩은 빈도 기반 무손실 압축 기법이다. 텍스트·로그·이미지 계수처럼 심볼 빈도가 치우친 데이터는 고정 길이 코드보다 평균 비트 수를 줄일 수 있음. CSPE 답안에서는 엔트로피 하한과 접두 부호 조건을 함께 제시해야 함.

## Ⅱ. 구조 및 구성요소

```text
+---------+    +-----------+    +--------------+    +------------+
| Symbols | -> | Frequency | -> | Huffman Tree | -> | Code Table |
+---------+    +-----------+    +--------------+    +------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 심볼 집합 | 압축 대상 문자·바이트·계수 | n개 심볼 |
| 빈도표 | 각 심볼의 출현 횟수 산출 | `p_i=f_i/Σf_i` |
| 우선순위 큐 | 낮은 빈도 노드 2개 반복 결합 | 시간복잡도 `O(n log n)` |
| 코드 테이블 | 트리 경로를 0/1 코드로 변환 | 접두 부호 보장 |

> 요약: 허프만 코딩은 빈도표를 우선순위 큐로 트리화하고, 트리 경로를 접두 코드 테이블로 변환함.

## Ⅲ. 동작원리 및 흐름도

```text
데이터 입력 -> 빈도 계산 -> 최소 빈도 2개 결합
       -> 루트 완성 -> 0/1 코드 부여 -> 비트열 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 심볼 빈도 계산 | 전체 빈도 합 `Σf_i` |
| 2 | 최소 빈도 노드 2개 선택 | 우선순위 큐 최소값 |
| 3 | 부모 노드 생성 후 재삽입 | 부모 빈도 = 두 자식 합 |
| 4 | 루트부터 0/1 코드 부여 | 접두 충돌 0건 |
| 5 | 원문을 코드 테이블로 치환 | 평균 길이 `L=Σp_i l_i` |

> 요약: 낮은 빈도 심볼을 트리 하단에 배치해 긴 코드를 주고, 높은 빈도 심볼에는 짧은 코드를 부여함.

## Ⅳ. 특징

| 구분 | 고정 길이 코드 | 허프만 코딩 | 수치 판단 |
|:---|:---|:---|:---|
| 코드 길이 | 모든 심볼 동일 | 빈도별 가변 길이 | 평균 `L`이 `ceil(log2 n)` 이하 가능 |
| 복호 조건 | 위치 기준 분할 | 접두 부호로 즉시 복호 | 접두 충돌 0건 |
| 압축 효과 | 분포 편향 미반영 | 빈도 편향 반영 | 영문 텍스트 8bit→약 4~5bit/문자 |
| 한계 | 구현 단순 | 트리·빈도표 저장 필요 | 작은 파일은 헤더 오버헤드 우세 |

> 요약: 허프만 코딩은 접두 부호로 무손실 복호를 보장하며, 심볼 분포가 치우칠수록 평균 비트 수 감소 폭이 커짐.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 로그·텍스트 압축은 바이트 빈도표를 블록 단위(예: 64KB)로 산출해 코드 테이블 오버헤드를 블록 크기 1% 이하로 제한
2. 이미지·영상 코덱은 DCT/양자화 후 계수 심볼에 허프만 코딩 적용, 반복 0 계수는 RLE와 결합
3. 저장·전송 시스템은 압축 전후 크기, 평균 코드 길이, 복호 CPU 사용률을 측정해 Gzip/Deflate 적용 여부 판단

**결론 (2줄):**
- 기술사 판단: 심볼 분포 편향이 크고 무손실이 필수이면 허프만, 확률 구간 표현까지 필요하면 산술 코딩을 선택함.
- 향후 방향: 범용 압축은 LZ 계열 사전 압축과 허프만 코딩을 결합해 중복 제거와 엔트로피 부호화를 함께 수행함.
