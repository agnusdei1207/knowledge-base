## Ⅰ. 개요
- **정의**: 심볼 출현 빈도에 따라 가변 길이 접두 코드를 부여하여 평균 부호 길이를 최소화하는 소스 코딩 기법
- **배경/필요성**: 고정 길이 부호는 빈도 차이를 활용하지 못해 엔트로피 H(031 참조) 이상으로 낭비가 발생하므로, 빈도 기반 가변 길이 부호가 필요함
- **비유**: 자주 쓰는 단축키는 키 하나로, 드물게 쓰는 기능은 메뉴를 여러 번 눌러 접근하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐욕 알고리즘과의 연계 | 빈도가 낮은 두 노드를 반복 병합하는 탐욕 선택(015 참조) | 탐욕 선택 속성과 최적 부분 구조를 함께 언급 |
| 접두 속성(prefix-free) | 어떤 코드도 다른 코드의 접두어가 아님 → 구분자 불필요 | "접두 코드"와 "가변 길이 코드"를 동의어로 쓰지 않을 것 |
| 최적성 조건 | 이산 무기억 정보원에서 심볼 단위 최적 코드임 | 블록 단위·산술 코딩과의 차이를 혼동하지 않을 것 |

> 요약: 빈도 기반 탐욕 병합으로 접두 속성을 유지하면서 평균 부호 길이를 최소화하는 기법임

## Ⅱ. 구성요소
```text
심볼 빈도 테이블
    |
    v
우선순위 큐(최소 힙)
    |
    v
반복 병합 --> 허프만 트리(이진 트리)
                |
                v
            코드 테이블(심볼 -> 가변 길이 비트열)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 빈도 테이블 | 각 심볼의 출현 횟수 또는 확률을 기록한 표 | 출석부에서 각 학생의 등교 횟수 |
| 우선순위 큐 | 빈도가 낮은 노드를 먼저 꺼내는 최소 힙 자료구조 | 대기열에서 번호가 작은 사람부터 호출 |
| 허프만 트리 | 리프가 심볼, 내부 노드가 병합 결과인 이진 트리 | 토너먼트 대진표(약한 팀부터 배치) |
| 코드 테이블 | 트리의 좌측 간선을 `0`, 우측 간선을 `1`로 매핑한 심볼별 비트열 | 주소록에서 이름-전화번호 매핑 |
| 접두 속성 | 리프에만 심볼이 존재하므로 한 코드가 다른 코드의 접두어가 되지 않음 | 전화번호가 다른 번호의 앞부분이 아닌 것 |

> 요약: 빈도 테이블 → 최소 힙 → 이진 트리 → 코드 테이블 순서로 접두 코드를 생성함

## Ⅲ. 절차
```text
1.빈도 집계 --> 2.힙 초기화 --> 3.반복 병합 --> 4.코드 할당
```
- 1단계: **빈도 집계** — 입력 데이터를 순회하며 각 심볼의 출현 빈도를 계산함
- 2단계: **힙 초기화** — 각 심볼을 단일 노드로 만들어 최소 힙에 삽입함 (노드 수 = 심볼 종류 수 n)
- 3단계: **반복 병합** — 힙에서 빈도가 가장 낮은 두 노드를 꺼내 합산 빈도의 부모 노드로 병합한 뒤 힙에 재삽입, 노드가 1개 남을 때까지 반복함 (n-1회)
- 4단계: **코드 할당** — 루트에서 리프까지 경로를 추적하여 좌측 `0`, 우측 `1`을 연결한 비트열을 각 심볼의 코드로 확정함

> 요약: 빈도 집계 → 최소 힙 → n-1회 병합 → 경로 기반 코드 할당의 4단계로 진행됨

## Ⅳ. 문제점
- **정적 빈도 의존**: 전체 데이터를 미리 스캔해야 빈도 테이블을 구성할 수 있어 스트리밍 입력에 적용이 어려움
- **심볼 단위 한계**: 심볼 하나의 정보량이 1 bit 미만이면 1 bit 코드를 할당할 수밖에 없어 엔트로피 H 대비 최대 1 bit/심볼의 낭비가 발생함
- **트리 전송 오버헤드**: 압축 데이터와 함께 허프만 트리(또는 빈도 테이블)를 전송해야 하므로 소규모 데이터에서는 오버헤드 비율이 커짐

> 요약: 정적 스캔 필요, 심볼 단위 1 bit 낭비, 트리 전송 부담이 실용적 한계임

## Ⅴ. 개선방안
1. 단기: 적응형(Adaptive) 허프만 도입 — 데이터를 수신하며 트리를 동적 갱신하여 사전 스캔 없이 스트리밍 압축을 지원함
2. 중기: 블록 허프만 또는 산술 코딩(Arithmetic Coding) 전환 — 심볼 그룹 단위로 부호화하여 1 bit/심볼 낭비를 해소함
3. 장기: 표준 코드북(Canonical Huffman) 적용 — 코드 길이 정보만 전송하여 트리 전송 오버헤드를 최소화함 (DEFLATE, JPEG 등에서 활용)

> 요약: 적응형 갱신, 블록/산술 코딩, 정규 허프만 순서로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 단독 사용보다 LZ77+허프만(DEFLATE), JPEG 등 복합 파이프라인의 엔트로피 코딩 단계로 지속 활용됨
- 기술사적 판단: 산술 코딩·ANS 등 엔트로피 한계에 더 근접하는 기법이 등장했으나, 구현 단순성과 특허 자유로 허프만은 표준 압축 포맷에서 여전히 채택됨
- 기술사 제언: 압축 시스템 설계 시 데이터 특성(심볼 분포 편향도, 스트리밍 여부)에 따라 허프만과 산술 코딩의 트레이드오프를 정량 비교하여 선택할 것을 권고함
