## Ⅰ. 개요
- **개요**: 키를 해시 함수로 배열 인덱스로 변환해 평균 `O(1)`에 삽입·조회·삭제하는 자료구조
- **배경/필요성**: 배열은 문자열·객체 같은 임의 키를 인덱스로 바로 쓸 수 없고, 이진 탐색 트리는 탐색에 `O(log N)`이 걸리므로, 임의 키를 고정 크기 인덱스로 직접 변환해 평균 `O(1)` 접근을 제공하는 구조가 필요함
- **출제 의도**: 해시 함수·충돌 처리·적재율 관리라는 내부 구조를 정확히 설명하고, 트리 계열 자료구조 대비 적용 조건을 판단할 수 있는지 확인
- **답안 방향**: 구조(해시 함수+버킷 배열) → 동작(인덱스 계산 → 충돌 처리 → 적재율 관리) → 비교(이진 탐색 트리 대비 선택 기준) 순으로 전개

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 구조 이해 및 비교 판단 | 해시 함수·충돌 해결(체이닝/오픈 어드레싱)·적재율 관리 | 충돌 해결 전략 혼동, 평균·최악 복잡도 미구분, "빠르다" 류 추상 표현 |

> 요약: 해시 테이블 답안은 "왜 O(1)인가"(해시 함수)와 "언제 O(1)이 깨지는가"(충돌·적재율)를 함께 보여야 완성됨.

## Ⅱ. 구조 및 구성요소
```text
key -> 해시 함수 h(k) -> 인덱스 -> 버킷 배열[인덱스]
                                       |
                                       +-> 충돌 발생 시 체이닝(연결 리스트 추가)
                                       +-> 또는 오픈 어드레싱(다음 빈 슬롯 탐색)
```

| 구성요소 | 역할 | 산출물/비유 |
|:---|:---|:---|
| `해시 함수 h(k)` | 임의 크기 키를 고정 크기 정수 인덱스로 변환 | 이름을 사물함 번호로 바꾸는 변환기 |
| `버킷 배열` | 인덱스별로 키-값 쌍을 저장하는 배열 | 번호가 매겨진 사물함 열 |
| `해시 충돌` | 서로 다른 키가 같은 인덱스로 매핑되는 상황 | 두 사람이 같은 사물함 번호를 받음 |
| `체이닝` | 충돌한 항목을 같은 버킷의 연결 리스트로 이어 저장하는 방식 | 사물함 하나에 여러 물건을 겹쳐 넣음 |
| `오픈 어드레싱` | 충돌 시 다음 빈 슬롯을 탐사해 저장하는 방식 | 사물함이 차 있으면 옆 칸을 빌림 |
| `적재율 α = N/M` | 저장 항목 수 `N` 대비 버킷 수 `M`의 비율, 충돌 확률과 직결 | 주차장의 만차율 |

> 요약: 해시 함수가 위치를 정하고, 체이닝·오픈 어드레싱이 그 위치의 충돌을 처리하며, 적재율이 두 방식 모두의 성능 한계를 좌우함.

## Ⅲ. 동작원리 및 흐름도
```text
key 입력 -> h(k) 계산 -> 버킷 인덱스 확인 -> 충돌 여부 판정
   -> (충돌 시 체이닝 또는 오픈 어드레싱) -> 적재율 검사 -> (임계값 초과 시 리사이징)
```

- 1단계 [키 입력 및 해시 계산]: 삽입·조회할 키 `k`에 대해 `h(k)`를 계산해 버킷 인덱스를 결정함
- 2단계 [버킷 접근 및 충돌 판정]: 해당 인덱스 슬롯을 확인하고, 이미 다른 키가 있는지 비교함
- 3단계 [충돌 해결]: 충돌 시 체이닝은 같은 슬롯의 연결 리스트에 항목을 추가하고, 오픈 어드레싱은 다음 빈 슬롯을 탐사해 저장함
- 4단계 [적재율 관리]: `α`가 임계값(통상 0.75)을 넘으면 버킷 배열을 2배로 확장하고 전체 항목을 재해싱함(리사이징)

> 요약: 해시 계산 → 충돌 판정 → 해결 → 적재율 검사의 4단계가 매 삽입·조회마다 반복되며, 리사이징만 임계값 초과 시에만 발생함.

## Ⅳ. 특징
- **평균 `O(1)` 접근**: 해시 함수가 키를 균등 분포로 매핑할 때 삽입·조회·삭제 모두 상수 시간
- **최악 `O(N)` 퇴화**: 모든 키가 같은 버킷에 몰리면 체이닝 리스트 전체를 순회해야 함
- **순서 미보장**: 해시값은 키의 대소 관계와 무관해 정렬·범위 조회(`10 ≤ key ≤ 20`)를 지원하지 않음
- **외부 입력 키 사용 시 위험**: 공격자가 의도적으로 같은 해시값을 만드는 키를 대량 투입하면 충돌이 집중되어 `O(N)`으로 퇴화시키는 공격이 가능함(해시 함수에 랜덤 시드를 넣는 방식으로 완화)

> 요약: 해시 테이블의 강점은 평균 성능이며, 최악 성능·순서 미지원·악의적 충돌 유발은 도입 전 반드시 점검할 한계임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 해시 테이블 | 이진 탐색 트리 | 선택 기준 |
|:---|:---|:---|:---|
| 평균 탐색 | `O(1)` | `O(log N)` | 정확한 키 일치 조회만 필요하면 해시 테이블 |
| 순서·범위 쿼리 | 미지원 | 지원(중위 순회, 범위 탐색) | 정렬·범위 조건이 있으면 이진 탐색 트리 |
| 최악 탐색 | `O(N)`(충돌 집중 시) | `O(log N)` 보장(균형 트리) | 최악 성능 보장이 중요하면 이진 탐색 트리 |

> 요약: 등호 비교(`=`)만 필요하면 해시 테이블, 순서·범위 연산이 필요하면 이진 탐색 트리를 선택함.

**리스크·대응 (불릿):**
- 해시 충돌 집중: 원인은 편향된 해시 함수 또는 악의적 키 투입 → 균등 분포 해시 함수와 랜덤 시드 적용으로 대응(지표: 최대 버킷 체인 길이)
- 적재율 방치: 원인은 리사이징 임계값 미설정 → 삽입 시점마다 적재율 검사 후 자동 리사이징 → 대응(지표: 현재 적재율 α)

**도입 후 점검 지표 (불릿):**
- 성능: 평균 탐색 연산 수 1~2회 유지 — 버킷별 체인 길이 모니터링으로 측정
- 운영: 적재율 임계값(0.75) 초과 빈도 — 리사이징 발생 횟수·소요 시간 측정

## Ⅵ. 실무 적용 및 결론
1. 단기: 조회 패턴이 등호 비교 위주인 구간을 식별해 해시 기반 자료구조(언어 기본 HashMap/dict) 적용 여부 진단
2. 중기: 외부 입력을 키로 쓰는 구간에 랜덤 시드 해시 함수 적용, 적재율 자동 리사이징 정책 수립
3. 장기: 분산 환경 확장 시 노드 간 키 재배치를 최소화하는 해시 기반 분산 기법으로 고도화

- 기술사적 판단: 등호 조회 중심·순서 무관 데이터는 해시 테이블, 정렬·범위 조회가 필요한 데이터는 이진 탐색 트리 계열을 선택함
- 기술사 제언: 해시 테이블 도입 시 평균 성능만 보지 말고 최악 시나리오(충돌 집중)와 외부 입력 노출 여부를 함께 점검해야 함
