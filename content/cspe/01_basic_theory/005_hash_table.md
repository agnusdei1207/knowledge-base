## 핵심 답안

해시 테이블은 키를 해시 함수로 버킷 위치에 매핑해 삽입, 조회, 삭제를 평균 `O(1)`에 처리하는 키-값 자료구조이며, 성능은 해시 함수의 분포 품질, 충돌 처리 방식, 적재율 관리에 의해 결정됨.

```text
Key -> Hash Function -> Bucket Index -> Collision Handling -> Value
```

기술사 답안에서는 "빠른 자료구조"라고만 쓰지 말고 **평균 `O(1)`의 조건**, **최악 충돌 시 `O(n)` 가능성**, **정렬·범위 질의 한계**를 함께 설명해야 함.

## 구성요소

| 구성요소 | 역할 | 판단 기준 |
|:---|:---|:---|
| 키(Key) | 값을 찾기 위한 식별자 | 동등성 비교와 해시 계산이 일관되어야 함 |
| 해시 함수 | 키를 해시값과 버킷 인덱스로 변환 | 균등 분포, 낮은 계산 비용, 공격 내성 |
| 버킷 배열 | 해시 결과가 접근하는 저장 공간 | 용량, 적재율, 캐시 효율 |
| 충돌 처리 | 같은 버킷에 여러 키가 모일 때 해결 | 체이닝, 개방 주소법, 재해싱 |
| 리사이즈 | 적재율 증가 시 버킷 수 확대 | 순간 지연과 메모리 피크 관리 |

자료구조용 해시 함수는 암호학적 안전성보다 빠른 계산과 균등 분포가 우선이지만, 외부 입력 키를 받는 서비스에서는 해시 플러딩 공격도 고려해야 함.

## 충돌 처리 방식

| 방식 | 원리 | 장점 | 주의점 |
|:---|:---|:---|:---|
| 체이닝 | 같은 버킷 원소를 리스트·트리로 연결 | 삭제가 단순하고 적재율 관리가 유연함 | 포인터 오버헤드, 캐시 미스 |
| 개방 주소법 | 충돌 시 다음 빈 슬롯을 탐사 | 배열 기반이라 캐시 효율이 좋음 | 탐사 길이 증가, 삭제 표시 관리 |
| 재해싱 | 버킷 수와 해시 매핑을 다시 구성 | 충돌 분포 개선 | 전체 재배치 비용 발생 |

충돌은 예외가 아니라 해시 테이블의 정상 운영 조건이므로, 답안에서는 충돌을 어떻게 감지하고 완화할지까지 써야 함.

## 자료구조 비교

| 구분 | 배열/리스트 | 균형 트리 | 해시 테이블 |
|:---|:---|:---|:---|
| 동등 검색 | `O(n)` | `O(log n)` | 평균 `O(1)` |
| 범위 검색 | 정렬 시 가능 | 강함 | 기본 구조는 약함 |
| 순서 보존 | 별도 정렬 필요 | 중위 순회 가능 | 보존하지 않음 |
| 갱신 비용 | 이동 또는 탐색 비용 | 회전·균형 유지 | 평균 빠르나 리사이즈 비용 |
| 선택 기준 | 소규모·순차 처리 | 정렬·범위 질의 | 캐시, 세션, 중복 검사, 딕셔너리 |

따라서 해시 테이블은 "키 존재 여부"와 "키로 값 찾기"가 핵심인 경우에 적합하고, 정렬된 출력이나 범위 질의가 핵심이면 트리나 정렬 인덱스를 비교해야 함.

## 운영 리스크와 대응

| 리스크 | 원인 | 대응 |
|:---|:---|:---|
| 충돌 집중 | 나쁜 해시 함수, 편향된 키 분포 | 해시 함수 개선, 시드 랜덤화, 최대 체인 길이 감시 |
| 리사이즈 지연 | 적재율 임계값 초과 | 초기 용량 산정, 점진 리사이즈, 용량 계획 |
| 순서 질의 부적합 | 키 순서를 저장하지 않음 | 균형 트리, B-Tree, 정렬 배열 병행 |
| 동시성 경합 | 같은 버킷 또는 전역 테이블 잠금 | 버킷 단위 잠금, 샤딩, lock-free 구조 |

해시 테이블은 평균 성능이 강점이지만, 최악 상황과 운영 지표를 관리하지 않으면 지연 스파이크가 발생할 수 있음.

## 오해와 감점 포인트

- **무조건 `O(1)` 표현**: 평균 `O(1)`이며 충돌 집중 시 최악 `O(n)`까지 나빠질 수 있음
- **범위 검색 오해**: 기본 해시 테이블은 정렬 순서를 보존하지 않으므로 범위·최소·최대 질의에 약함
- **해시 함수 목적 혼동**: 암호학적 해시와 자료구조용 해시는 요구사항이 다름
- **적재율 누락**: 버킷 수 대비 원소 수를 관리하지 않으면 평균 성능 가정이 무너짐
- **동등성 규칙 불일치**: 같은 키로 판단되는 값은 같은 해시 결과를 가져야 함

## 답안 작성 포인트

1. 정의는 "키를 해시 함수로 버킷에 매핑해 평균 `O(1)` 접근을 제공하는 키-값 자료구조"로 씀
2. 구성은 키, 해시 함수, 버킷, 충돌 처리, 적재율로 도식화함
3. 충돌 처리 방식은 체이닝과 개방 주소법을 비교함
4. 균형 트리와 비교해 동등 검색과 범위 검색의 차이를 설명함
5. 결론은 "평균 성능은 강하지만 충돌·리사이즈·순서 질의 요구를 운영 기준으로 관리해야 한다"로 마무리함

> 기술사 관점에서 해시 테이블은 평균 성능 암기가 아니라 키 분포, 충돌, 적재율, 질의 유형을 기준으로 선택해야 하는 자료구조임.
