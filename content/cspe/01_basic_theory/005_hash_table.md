## 미리 알고가기

- 해시 함수: 키를 해시값으로 바꿔 버킷 인덱스를 계산하는 함수임
- 충돌(Collision): 서로 다른 키가 같은 버킷 인덱스로 매핑되는 현상임
- 버킷(Bucket): 키·값 또는 충돌 체인을 저장하는 배열 슬롯임
- 적재율(Load Factor): 버킷 수 대비 원소 수의 비율이며 재해싱 시점 판단 지표임
- 재해싱(Rehashing): 버킷 수를 늘린 뒤 기존 키를 새 인덱스로 다시 배치하는 작업임
- HashDoS: 공격자가 충돌 키를 집중시켜 해시 연산을 최악 시간으로 퇴화시키는 서비스 거부 공격임

## 작성 근거(검토용)

- **개요 구성**: 키-버킷 매핑과 키·값 저장을 함께 정의해 평균 조회 지연이 낮아지는 구조를 드러냄
- **특징 선정**: 분산, 충돌 처리, 재해싱, 순서 손실이 성능과 적용 범위를 실제로 바꿈
- **Ⅲ 비교축**: 균형 트리와 정렬 배열을 함께 둬 단건 조회·범위 검색·읽기 전용 조회를 구분함
- **구조 도식**: 키에서 해시 함수, 버킷 인덱스, 충돌 구조로 이어지는 저장 경로를 보이기 위해 배치함
- HashDoS와 재해싱은 평균 성능이 깨지는 대표 조건이라 지연 지표로 연결함

## Ⅰ. 개요

- **정의/개념**: 해시 테이블은 해시 함수로 키를 버킷 인덱스로 매핑하고 키·값을 저장해 단건 조회·삽입·삭제 지연을 낮추는 자료구조임
- **배경/필요성**: 세션·캐시·중복 검사의 단건 조회 지연을 줄이기 위해 충돌을 통제하는 인덱싱 구조가 필요함

## Ⅱ. 특징

- 해시값이 버킷에 고르게 분산되고 적재율이 낮으면 삽입·삭제·조회가 평균 $O(1)$에 가까움
- 충돌 해결 방식이 체인 길이와 탐사 횟수를 결정해 최악 지연을 좌우함
- 적재율 임계치를 넘으면 재해싱으로 평균 성능을 회복하지만 순간 갱신 지연이 커짐
- 기본 해시 구조는 키 순서를 보장하지 않아 범위 질의와 정렬 순회에 부적합함

## Ⅲ. 종류 및 비교

| 판단 기준 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 (AVL/RB) | 정렬 배열 (Sorted Array) |
|:---|:---|:---|:---|
| **조회 성능** | 평균 $O(1)$·최악 $O(n)$ | 평균·최악 $O(\log n)$ | $O(\log n)$ (이진 탐색) |
| **순서 보전** | 기본적으로 보장하지 않음 | 중위 순회로 보장 | 인덱스 순차 접근으로 보장 |
| **갱신 비용** | 평균 $O(1)$, 재해싱 순간 비용 | 회전·재색칠로 $O(\log n)$ 유지 | 삽입·삭제 시 데이터 이동 큼 |
| **주요 용도** | 단건 조회, 캐시, 중복 검사 | 범위 검색, 정렬 유지 | 읽기 전용 참조 데이터 |

> 요약: 단건 키 조회는 해시 테이블, 범위 검색은 균형 트리, 읽기 전용 정렬 조회는 정렬 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 해시 함수 | 키를 버킷 인덱스로 변환하며 분산 품질이 체인 길이와 탐사 횟수를 좌우함 |
| 버킷 배열 | 키·값 또는 충돌 구조의 시작점을 보관하는 고정 크기 슬롯 집합임 |
| 충돌 해결 구조 | 체이닝 또는 개방 주소법으로 같은 인덱스의 키를 구분해 저장함 |
| 적재율 기준 | 버킷 대비 원소 수를 감시해 재해싱 시점과 평균 지연을 통제함 |
| 키 비교 | 같은 해시값 안에서 실제 키 일치 여부를 확인해 오조회 위험을 방지함 |

```text
[ 해시 처리 구조 ]
+-----+      +---------------+      +--------------+      +--------------+
| 키  | ---> | 해시 함수     | ---> | 버킷 인덱스 | ---> | 버킷 배열   |
+-----+      +---------------+      +--------------+      +--------------+
                                                          |
                                                          v
                                                  값·충돌 체인
```

> 요약: 해시 테이블은 키를 버킷으로 분산시키고 충돌 구조에서 실제 키를 검증함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 해시값 생성  | --> | 인덱스 매핑   | --> | 충돌 여부 확인 | --> | 데이터 입출력 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **해시 생성** — 입력 키로 버킷 계산용 해시값을 산출함
2. **인덱스 매핑** — 해시값을 배열 크기에 맞춰 버킷 인덱스로 변환함
3. **충돌 처리** — 같은 인덱스의 기존 키를 체인 또는 탐사 순서로 확인함
4. **키 검증·반환** — 실제 키 일치 후 값을 갱신하거나 조회 결과를 반환함

> 요약: 키를 버킷 인덱스로 변환한 뒤 충돌 구조에서 실제 키를 확인해 값을 갱신하거나 반환함.

## Ⅵ. 실무 사례

1. 웹 요청 파라미터 맵은 해시 무작위화와 체인 트리화로 HashDoS에 대응하고 충돌률·p99 지연을 확인함
2. 캐시는 예상 원소 수로 초기 버킷을 정하고 재해싱 횟수·최대 갱신 지연을 확인함

## Ⅶ. 결론

- 해시 테이블은 단건 키 조회 지연을 낮추지만 해시 분산도·충돌 처리·적재율 관리가 평균 성능 유지 조건임
