# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 키(Key)를 **해시 함수(Hash Function)**를 통해 특정 숫자(Index)로 변환하여, 해당 위치에 데이터를 저장하고 검색하는 자료구조.
- **핵심 특징**: 평균 **$O(1)$**의 경이로운 탐색 속도를 보장함. (비교가 아닌 '계산'에 의한 접근)
- **핵심 직관**: "찾지 마라, 계산해서 바로 가라." (사물함 번호를 이름으로 계산해서 여는 방식)

## 핵심 용어 정리

| 용어 | 의미 | 비유/예시 |
|:---|:---|:---|
| **해시 함수** | 임의의 길이를 가진 키를 고정된 범위의 정수로 매핑 | 사물함 번호 계산기 |
| **충돌 (Collision)** | 서로 다른 키가 같은 해시 값을 가지는 현상 | 두 명의 이름이 같은 사물함 번호로 나옴 |
| **버킷 (Bucket)** | 데이터가 실제로 저장되는 배열의 한 칸 | 번호가 매겨진 사물함 한 칸 |
| **로드 팩터 (Load Factor)** | 전체 버킷 중 사용 중인 비율 ($\alpha = n/m$) | 사물함이 얼마나 찼는가? (밀집도) |
| **리해싱 (Rehashing)** | 테이블이 너무 차면 용량을 늘리고 데이터를 재배치 | 사물함이 꽉 차서 더 큰 곳으로 이사 |

## 깊이 이해

- **왜 O(1)인가?**: 
  이진 탐색은 $O(\log N)$의 비교를 수행하지만, 해시는 `index = hash(key) % size`라는 단 한 번의 연산으로 저장 위치를 확정합니다. 데이터가 1억 개든 1조 개든, 함수 계산 시간만 일정하다면 탐색 시간은 항상 일정합니다.

- **필연적 숙명: 충돌(Collision)**: 
  비둘기집 원리에 의해, 키의 집합이 버킷의 수보다 크면 충돌은 반드시 발생합니다. 이를 어떻게 우아하게 해결하느냐가 성능의 관건입니다.
  - **Chaining**: 같은 주소에 연결 리스트(Linked List)로 데이터를 줄줄이 매담. (자바의 `HashMap`)
  - **Open Addressing**: 충돌 시 옆 칸(Linear Probing), 혹은 멀리(Quadratic, Double Hashing) 빈 칸을 찾아 떠남.

- **해시 함수의 요건**:
  1. **결정론적(Deterministic)**: 같은 키에는 항상 같은 인덱스.
  2. **균등 분산(Uniformity)**: 버킷 전역에 골고루 뿌려야 충돌이 적음.
  3. **고속 계산**: 함수 자체가 너무 무거우면 $O(1)$의 의미가 퇴색됨.

- **주의점 (해시 DoS 공격)**: 
  악의적으로 충돌을 유발하는 키 세트($O(N)$으로 퇴화됨)를 대량 전송하여 서버 CPU를 100% 점유시키는 공격. 최신 언어들은 이를 막기 위해 해시 함수에 **Random Seed**를 섞습니다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 키를 인덱스로 변환하는 **상수 시간 연산($O(1)$)**을 통해 비교 기반 탐색의 물리적 한계를 극복한 자료구조임.
> 2. **가치**: 캐시(Redis), 세션 관리, DB 인덱스, 암호학적 검증 등 현대 소프트웨어 아키텍처의 성능을 지탱하는 핵심 엔진임.
> 3. **판단 포인트**: 데이터 밀도($\alpha$)에 따른 **충돌 해결 전략**과 **리해싱 시점**의 조율이 실무적 성능 튜닝의 핵심임.

## Ⅰ. 비교를 넘어선 상수 시간 탐색, 해시 테이블의 개요
### 1. 정의
- 해시 함수를 사용하여 키를 배열의 인덱스로 매핑함으로써, 데이터의 삽입, 삭제, 탐색을 평균 $O(1)$에 수행하는 자료구조.
### 2. 필요성
- **대규모 조회 성능**: 데이터 양과 무관한 일정한 응답 속도 보장.
- **자원 효율성**: 정렬 비용이 큰 환경에서 비교 연산 없이 즉각적인 접근 필요.

## Ⅱ. 해시 테이블의 메커니즘 및 구성 요소
### 1. 해싱 프로세스
```text
  [Key] -> [Hash Function] -> [Hash Value] -> [Modular Size] -> [Bucket Index]
```
### 2. 주요 구성 요소
- **해시 함수(Hash Function)**: 키를 정수 값으로 변환하는 변환기.
- **버킷(Bucket) / 슬롯(Slot)**: 데이터가 저장되는 실제 메모리 공간.
- **충돌 해결기(Collision Resolver)**: 동일 주소 충돌 시 우회 경로를 제공하는 로직.

## Ⅲ. 충돌 해결 기법(Collision Resolution) 비교 분석
| 구분 | 개별 체이닝 (Chaining) | 개방 주소법 (Open Addressing) |
|:---:|:---|:---|
| **기본 원리** | 버킷을 연결 리스트로 구현 | 빈 버킷을 찾아 재배치 |
| **탐사 방식** | 리스트 추적 | 선형(Linear), 이차(Quadratic), 이중 해싱 |
| **장점** | 삽입/삭제 단순, $\alpha > 1$ 가능 | 포인터 오버헤드 없음, 캐시 지역성 우수 |
| **단점** | 메모리 동적 할당 오버헤드 | 데이터 밀집 시 클러스터링(Clustering) 발생 |
| **적용 사례** | **Java HashMap**, 대규모 가변 데이터 | **Python Dict**, 캐시 지역성 중시 환경 |

## Ⅳ. 성능 유지의 관건: 로드 팩터와 리해싱
### 1. 로드 팩터 ($\alpha$) 관리
- 적재율 $\alpha = n/m$이 커질수록 충돌 확률이 급증하여 $O(1) \rightarrow O(N)$으로 성능 퇴화.
- 실무 임계치: 통상 **0.7~0.75** 도달 시 확장을 고려.
### 2. 리해싱 (Rehashing)
- 테이블 크기를 약 2배로 늘리고, 새로운 해시 함수(혹은 커진 Modular)로 모든 데이터를 재배치.
- **비용**: $O(N)$의 일시적 지연 발생. 이를 분산하기 위해 **점진적 리해싱(Incremental Rehashing)** 기법 활용.

## Ⅴ. 실무적 고려사항 및 보안 위협
### 1. 해시 DoS (Denial of Service) 공격
- 해시 충돌이 빈번한 데이터를 의도적으로 주입하여 서비스를 마비시키는 공격.
- **대응**: **Hash Seed Randomization** 적용, 충돌 시 연결 리스트 대신 **자가 균형 이진 탐색 트리(Treeify)**로 전환. (자바 8 이상 $O(\log N)$ 보장)
### 2. 일관된 해싱 (Consistent Hashing)
- 분산 시스템에서 서버 노드 추가/삭제 시 데이터 이동을 최소화하기 위한 해싱 기법.
- **용도**: 카산드라(Cassandra), 다이나모DB(DynamoDB) 등의 샤딩 메커니즘.

## Ⅵ. 기술사 관점의 결론: "속도와 견고함의 균형"
- 해시 테이블은 응답 속도 극대화를 위한 최강의 도구이나, **충돌 관리와 보안**이라는 숙제를 항상 동반함.
- 아키텍트는 비즈니스 요구사항에 따라 **등가 조회($O(1)$)는 해시**를, **범위 조회($O(\log N)$)는 B-Tree**를 선택하는 적재적소의 판단력이 필수임.
