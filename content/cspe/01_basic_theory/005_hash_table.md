## Ⅰ. 개요
- 키(Key)를 해시 함수로 변환하여 주소로 사용, 데이터를 저장하는 구조임.
- 평균 O(1)의 속도로 데이터 삽입, 삭제, 탐색이 가능함.
- [표] 출제 의도: 고속 데이터 접근 및 충돌 해결 메커니즘 설계 능력 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  Key -> [ Hash Function ] -> Index -> [ Bucket/Slot ]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Hash Function | 키를 고정된 길이의 주소로 변환하는 함수 | 분류기 |
| Bucket | 실제 데이터가 저장되는 공간 | 사물함 |
| Collision | 서로 다른 키가 동일한 인덱스로 배정됨 | 사물함 중복 |

> 요약: 매핑을 통해 직접 주소 방식의 메모리 낭비를 줄이고 속도 확보함.

## Ⅲ. 절차
- ASCII 흐름도
  Input Key -> Calc Hash -> Check Collision -> Store/Retrieve

1. 입력받은 키를 해시 함수에 대입하여 인덱스를 산출함.
2. 해당 인덱스에 데이터가 있는지(충돌 여부) 확인함.
3. 충돌 발생 시 Chaining이나 Open Addressing으로 해결함.
4. 최종 위치에 값을 저장하거나 해당 위치의 값을 반환함.

> 요약: 해시 함수를 통한 주소 계산과 충돌 처리가 핵심임.

## Ⅳ. 문제점
- 해시 함수 성능 저하 시 충돌이 빈번해져 탐색 속도가 O(n)으로 하락함.
- 클러스터링(Clustering) 현상 발생 시 특정 구간에 데이터가 집중됨.

## Ⅴ. 개선방안
- 단기: 이중 해싱(Double Hashing) 도입으로 클러스터링 방지함.
- 중기: 동적 로드 밸런싱을 통한 테이블 리사이징(Resizing) 실시함.
- 장기: 암호학적 해시 알고리즘 활용으로 균등 분포 유도함.

## Ⅵ. 전망
- 스마트 NIC와 같은 하드웨어 가속기에서 실시간 패킷 분류를 위한 고정 시간(Constant Time) 해싱 기술이 네트워크 보안의 CSF로 자리 잡을 것임.
- 읽기 전용 대규모 데이터셋에 대해 충돌이 전혀 없는 '완벽 해싱(Perfect Hashing)'을 생성하는 AI 최적화 도구들이 데이터 엔지니어링의 표준이 될 것임.
- 분산 원장 기술(DLT)에서 샤딩 성능 향상을 위해 일관된 해싱(Consistent Hashing)의 지연 시간을 최소화하는 프로토콜 혁신이 지속될 전망임.
