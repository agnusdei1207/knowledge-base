# 해시 테이블 (Hash Table)

## 1. 개요

- **정의/개념**: 해시 테이블은 키를 해시 함수로 버킷 위치에 매핑해 삽입·검색·삭제를 평균 `O(1)`에 처리하는 키-값 자료구조이다.
- **배경/필요성**: 배열·트리 기반 검색은 비교 비용이 누적되므로, 동등 검색 중심 업무에서는 키를 저장 위치로 직접 변환하는 구조가 필요하다.

## 2. 특징 및 비교

| 구분 | 배열/리스트 | 균형 트리 | 해시 테이블 |
|---|---:|---:|---:|
| 동등 검색 | `O(n)` | `O(log n)` | 평균 `O(1)` |
| 범위 검색 | 정렬 시 가능 | 우수 | 기본적으로 부적합 |
| 정렬 순회 | 별도 정렬 필요 | 가능 | 보장하지 않음 |
| 삽입·삭제 | 탐색·이동 비용 | 균형 유지 비용 | 평균 빠름, 리사이즈 비용 |
| 주요 용도 | 소규모 데이터 | 범위 질의 | 캐시, 세션, 중복 검사 |

해시 테이블은 키 존재 여부와 값 조회가 핵심인 경우 강하지만, 정렬 순서와 범위 질의는 약하다.

선택 시에는 동등 검색 비중, 범위 질의 필요성, 충돌률, 적재율, 메모리·캐시 특성, 동시 접근 조건을 함께 판단한다.

이 선택 기준은 해시 함수, 버킷, 충돌 처리, 리사이즈 정책으로 구현되며, 각 요소가 평균 `O(1)` 성능의 전제이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| 키(Key) | 값을 찾기 위한 식별자 | 동등성 비교 기준 |
| 해시 함수 | 키를 해시값·버킷 인덱스로 변환 | 균등 분포, 계산 비용 |
| 버킷 | 실제 저장 위치 | 용량과 적재율 |
| 충돌 처리 | 같은 버킷에 여러 키가 모일 때 해결 | 체이닝, 개방 주소법 |
| 리사이즈 | 적재율 증가 시 버킷 확장 | 순간 지연 관리 |

| 방식 | 원리 | 장점 | 단점 |
|---|---|---|---|
| 체이닝 | 같은 버킷 원소를 연결 | 삭제 단순 | 포인터 오버헤드 |
| 개방 주소법 | 빈 슬롯을 탐사 | 캐시 친화적 | 탐사 길이 증가 |
| 재해싱 | 버킷 수·매핑 재구성 | 분포 개선 | 전체 재배치 비용 |

따라서 해시 테이블의 문제점은 대부분 평균 성능을 만드는 전제, 즉 분포·적재율·충돌 관리가 무너질 때 발생한다.

## 4. 문제점 및 개선방안

1. **충돌 집중**
   - 해시 함수 분포가 나쁘면 특정 버킷에 원소가 몰려 최악 `O(n)`이 된다.
   - **개선방안**: 해시 함수 개선, 시드 랜덤화, 최대 체인 길이 모니터링을 적용한다.

2. **리사이즈 지연**
   - 적재율 초과 시 전체 원소 재배치로 지연 스파이크가 발생할 수 있다.
   - **개선방안**: 초기 용량 산정, 점진 리사이즈, 적재율 기준 관리를 적용한다.

3. **순서 질의 부적합**
   - 기본 해시 테이블은 키 순서를 보존하지 않는다.
   - **개선방안**: 범위 질의가 핵심이면 균형 트리, B-Tree, 정렬 인덱스를 사용한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 캐시·세션 저장소 | 사용자 ID나 토큰을 키로 평균 `O(1)` 조회 | hit ratio, p99 지연 |
| 중복 제거 | 이벤트 키를 해시로 저장해 중복 여부 판단 | 충돌률, 처리량 |
| 분산 캐시 | 일관 해싱으로 노드 추가·제거 시 재배치 최소화 | 재배치 비율, 노드 부하 |

## 6. 결론

해시 테이블은 동등 검색 중심 업무에서 매우 강력한 자료구조이다. 평균 `O(1)` 성능은 해시 함수 품질, 충돌 처리, 적재율, 리사이즈, 동시성 정책이 관리될 때 성립하며, 범위 질의 한계는 트리 구조와 비교해야 한다.
