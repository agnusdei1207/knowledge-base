## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 해시 함수를 통해 키를 배열 인덱스로 변환하여 평균 O(1)에 삽입·탐색·삭제를 수행하는 자료구조임 |
| **배경/필요성** | 대량 데이터에서 키 기반 직접 접근이 필요하며, 트리 탐색 O(log n)보다 빠른 상수 시간 연산이 요구됨 |
| **출제 의도** | 해시 충돌 해결 기법(체이닝·개방 주소법)과 해시 함수 설계 원칙을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 해시함수  | --> |  버킷    | --> | 충돌해결  |
| h(key)   |     | (슬롯배열)|     | (Chain/  |
|          |     |          |     |  Open)   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 해시 함수 | 키를 정수 인덱스로 변환하는 함수로, 균일 분포·결정적 출력이 필수임 | 사물함 번호 배정 규칙 |
| 버킷(슬롯) | 해시값에 대응하는 배열 위치로, 키-값 쌍을 저장함 | 사물함 칸 |
| 충돌 해결 | 서로 다른 키가 같은 인덱스에 매핑될 때의 처리 기법임 | 같은 사물함에 두 짐이 배정될 때 해결책 |

> 요약: 해시 함수(인덱스 변환) + 버킷(저장) + 충돌 해결(체이닝/개방 주소)로 O(1) 접근을 구현함.

## Ⅲ. 절차
```
+------------+     +------------+
| 키 입력    | --> | 해시함수   |
|            |     | h(key)계산 |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 값 반환    | <-- | 버킷접근  |
| /저장      |     | 충돌처리   |
+------------+     +------------+
```

1. 해시 계산: 키를 해시 함수에 입력하여 정수 해시값을 산출함
2. 인덱스 매핑: `index = h(key) % table_size`로 버킷 위치를 결정함
3. 충돌 확인: 해당 버킷에 다른 키가 존재하면 체이닝(연결 리스트) 또는 개방 주소법(선형/이차 탐사)으로 처리함
4. 연산 수행: 삽입·탐색·삭제를 해당 버킷에서 수행하고 결과를 반환함

> 요약: 해시 계산 → 인덱스 매핑 → 충돌 처리 → 연산 수행으로 상수 시간 접근을 달성함.

## Ⅳ. 문제점
- 충돌 집중: 해시 함수 품질이 낮으면 특정 버킷에 키가 집중되어 O(n)으로 퇴화함
- 리사이징 비용: 적재율(Load Factor) 초과 시 테이블 확장·재해싱에 O(n)이 소요됨
- 순서 미보장: 삽입 순서·키 정렬 순서가 보장되지 않아 범위 탐색이 불가함

## Ⅴ. 개선방안
- (단기) 좋은 해시 함수: MurmurHash·xxHash 등 균일 분포 해시 함수를 사용하여 충돌을 줄임
- (중기) 점진적 리사이징: 한 번에 전체 재해싱 대신 삽입마다 일부 버킷을 이전하여 지연을 분산함
- (장기) Cuckoo Hashing: 두 해시 함수를 사용하여 최악 O(1) 탐색을 보장하는 기법을 적용함

## Ⅵ. 전망
- 인메모리 DB·캐시 시스템(Redis·Memcached)의 핵심 자료구조로 해시 테이블이 활용되며, FPGA·GPU 기반 하드웨어 해시 가속이 확산될 전망임
