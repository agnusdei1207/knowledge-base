## 미리 알고가기

- 해시 함수: 키를 해시값으로 바꿔 버킷 인덱스를 계산하는 함수임
- 충돌(Collision): 서로 다른 키가 같은 버킷 인덱스로 매핑되는 현상임
- 버킷(Bucket): 키·값 또는 충돌 체인을 저장하는 배열 슬롯임
- 탐사(Probing): 충돌 시 정해진 규칙으로 다음 빈 버킷을 찾는 개방주소법의 절차임
- 적재율(Load Factor): 버킷 수 대비 원소 수의 비율이며 재해싱 시점 판단 지표임
- 재해싱(Rehashing): 버킷 수를 늘린 뒤 기존 키를 새 인덱스로 다시 배치하는 작업임
- 해시 서비스 거부 공격(HashDoS): 충돌 키를 집중시켜 해시 테이블 연산을 최악 시간으로 퇴화시키는 공격임
- 버킷 트리화(Treeification): 충돌 체인이 길어진 버킷을 균형 트리로 바꿔 최악 조회 비용을 줄이는 방식임
- AVL·레드-블랙 트리: 높이를 제한해 조회·삽입·삭제를 $O(\log n)$에 수행하는 균형 이진 탐색 트리임

## 작성 근거(검토용)

- **방향성**: 해시 테이블은 평균 $O(1)$ 조회를 얻는 대신 충돌이 몰리면 최악 $O(n)$으로 퇴화하므로, 외부 입력을 키로 쓸 때는 해시 무작위화·적재율 상한·재해싱 정책으로 최악 상황을 미리 통제해야 함
- **개요 구성**: 키를 버킷 인덱스로 매핑하는 과정과 키·값 저장을 함께 정의해 단건 조회·삽입·삭제 지연이 낮아지는 구조를 드러냄
- **Ⅱ. 특징 선정**: 분산, 충돌 처리, 재해싱, 순서 손실이 성능과 적용 범위를 실제로 바꿈
- **Ⅲ. 비교축 선정**: 적용 기준, 조회 비용, 주요 제약은 해시와 순서 기반 구조의 선택을 가름
- **Ⅳ. 구조 선정**: 키에서 해시 함수, 버킷 인덱스, 충돌 구조로 이어지는 저장 경로를 보이기 위해 배치함
- **Ⅵ. 실무 사례 선정**: HashDoS와 재해싱은 평균 성능이 깨지는 대표 조건이라 지연 지표로 연결함
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 평균·최악 성능 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 해시 테이블은 해시 함수로 키를 버킷 인덱스로 매핑하고 키·값을 저장해 단건 조회·삽입·삭제 지연을 낮추는 자료구조임
- **배경/필요성**: 세션·캐시·중복 검사의 단건 조회 지연을 줄이기 위해 충돌을 통제하는 인덱싱 구조가 필요함

### 쉽게 이해하기 (학습용)
- 사물함 번호를 이름으로 바로 계산해 그 칸에 물건을 넣으면, 찾을 때도 같은 계산으로 곧장 그 칸을 여는 것과 같음

## Ⅱ. 특징

- 해시값이 버킷에 고르게 분산되고 적재율이 낮으면 삽입·삭제·조회가 평균 $O(1)$에 가까움
- 충돌 해결 방식이 체인 길이와 탐사 횟수를 결정해 최악 지연을 좌우함
- 적재율 임계치를 넘으면 재해싱으로 평균 성능을 회복하지만 순간 갱신 지연이 커짐
- 기본 해시 구조는 키 순서를 보장하지 않아 범위 질의와 정렬 순회에 부적합함

### 쉽게 이해하기 (학습용)
- 사물함 번호가 골고루 퍼져 있고 칸이 넉넉하면 거의 바로 찾아 넣고 뺄 수 있음
- 같은 번호로 계산된 물건이 여러 개 몰리면 그 안에서 다시 뒤져야 하므로 느려짐
- 칸이 거의 다 차면 사물함 전체를 더 큰 것으로 바꾸고 번호를 다시 매겨야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 | 정렬 배열 (Sorted Array) |
|:---|:---|:---|:---|
| **적용 기준** | 순서 무관한 단건 키 조회 | 정렬 순서·범위 탐색이 필요한 조회 | 삽입이 드물고 조회가 압도적으로 많은 경우 |
| **조회 비용** | 평균 $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| **주요 제약** | 충돌 집중 시 $O(n)$ 퇴화 | 갱신 시 회전·재색칠 비용 | 중간 삽입 시 $O(n)$ 이동 |

> 요약: 순서 없는 단건 조회는 해시 테이블, 정렬 순서·범위 탐색이 필요하면 균형 이진 탐색 트리, 삽입이 드물고 조회 위주면 정렬 배열을 씀.

### 쉽게 이해하기 (학습용)
- 번호 계산으로 바로 칸을 여는 방법(해시), 이름을 비교하며 나뭇가지를 타고 내려가는 방법(균형 트리), 가운데부터 반씩 좁혀가는 방법(정렬 배열)은 상황에 따라 유불리가 다름

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 해시 함수 | 키를 버킷 인덱스로 변환하는 함수 |
| 버킷 배열 | 키·값 엔트리를 저장하는 슬롯 집합 |
| 충돌 해결 구조 | 동일 인덱스의 키를 구분하는 저장 구조 |
| 적재율 기준 | 버킷 수 대비 원소 수의 재해싱 판단값 |

> 요약: 해시 테이블은 해시 함수로 버킷을 선택하고 충돌 구조에서 키를 검증하며 적재율로 재해싱을 결정함.

### 쉽게 이해하기 (학습용)
- 이름을 번호로 바꾸는 계산기(해시 함수), 번호별 칸들(버킷 배열), 같은 번호에 몰린 물건을 정리하는 방법(충돌 해결 구조), 칸이 얼마나 찼는지 재는 눈금(적재율)이 함께 작동함

## Ⅴ. 원리 및 절차 흐름도

```text
키 입력 → 해시값·버킷 계산 → 엔트리 확인
                           ├─ 키 일치 → 값 조회·갱신
                           ├─ 빈 위치 → 삽입·조회 실패
                           └─ 다른 키 → 다음 체인·탐사 위치 확인
```

1. **해시값 생성**: 입력 키로 버킷 계산용 해시값을 산출함
2. **인덱스 매핑**: 해시값을 배열 크기에 맞춰 버킷 인덱스로 변환함
3. **충돌 처리**: 같은 인덱스의 기존 키를 체인 또는 탐사 순서로 확인함
4. **키 검증·값 처리**: 실제 키 일치 후 값을 갱신하거나 조회 결과를 반환함

> 요약: 키를 버킷 인덱스로 변환한 뒤 충돌 구조에서 실제 키를 확인해 값을 갱신하거나 반환함.

### 쉽게 이해하기 (학습용)
- 이름을 번호로 계산하고, 그 번호의 칸을 찾아가고, 이미 다른 물건이 있으면 정해둔 방법으로 다시 찾고, 마지막에 진짜 내 물건이 맞는지 확인하는 순서임

## Ⅵ. 실무 사례

1. 웹 요청 파라미터 맵은 해시 무작위화와 버킷 트리화로 의도적인 충돌 공격에 대응함
2. 캐시는 예상 원소 수에 맞춰 초기 버킷을 확보해 반복 재해싱을 줄임

### 쉽게 이해하기 (학습용)
- 악의적으로 같은 번호에 물건을 몰아넣으려는 시도를 막기 위해 번호 계산 방식을 바꾸거나, 손님이 몰릴 걸 미리 알고 사물함을 넉넉히 준비해두는 것과 같음

## Ⅶ. 결론

- 해시 테이블은 키를 저장 위치로 바로 연결해 조회를 빠르게 하며, 충돌이 한곳에 몰리지 않도록 관리해야 함
- 외부 입력을 키로 받을 때는 평균 조회 성능만 믿지 말고 해시 무작위화·적재율 상한·재해싱 정책으로 최악 상황을 통제해야 함

### 쉽게 이해하기 (학습용)
- 평소엔 번호만 알면 바로 칸을 열 수 있어 편리하지만, 누군가 일부러 번호를 몰아넣으려 하면 대비책을 미리 마련해둬야 함
