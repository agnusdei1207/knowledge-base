# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 키(Key)를 해시 함수에 넣어 얻은 값(Hash)을 인덱스 삼아 값(Value)을 저장하는 O(1) 자료구조
- **왜 필요한가**: 수억 건의 데이터 중 특정 유저 정보를 찾을 때 배열 순차 탐색이나 트리 탐색을 거치지 않고, 키를 넣으면 즉시 메모리 주소가 튀어나오게 하여 지연 시간을 없애기 위함.
- **핵심 직관**: 대형 도서관에서 책을 찾을 때 목차를 뒤지는 게 아니라, 책 제목을 계산기(해시함수)에 넣었더니 정확한 위치 좌표가 나와 바로 찾아가는 마법이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 해시 함수 | Key를 정수 인덱스로 변환 | 이름을 넣으면 방 번호가 나오는 계산기 |
| 버킷(Bucket) | 값(Value)을 저장하는 배열 칸 | 호텔의 각 방 |
| 충돌(Collision) | 다른 Key가 같은 인덱스로 감 | 두 손님이 같은 방을 배정받음 |
| 체이닝(Chaining) | 충돌 시 그 칸에 리스트로 매닮 | 같은 방에 2층 침대를 더 놓음 |
| 개방 주소법(Open Addressing) | 충돌 시 옆 빈칸을 찾아 저장 | 옆의 빈방으로 안내 |

## 깊이 이해

### O(1)이 어떻게 가능한가 (핵심 원리)
- Key를 해시 함수에 넣어 큰 정수(해시 코드)를 얻고, 그것을 버킷 개수로 나눈 나머지(mod)를 인덱스로 쓴다. 인덱스가 정해지면 배열 접근이라 계산 한 번에 위치가 나온다 → 평균 O(1).
- 좋은 해시 함수는 Key들을 버킷에 고르게 흩뿌린다. 한쪽으로 쏠리면 특정 버킷만 길어져 느려진다.

### 충돌은 왜 반드시 생기나
- 가능한 Key는 사실상 무한한데 버킷은 유한하다(비둘기집 원리). 서로 다른 Key가 같은 인덱스로 가는 충돌은 피할 수 없어 대응책이 필수다.

### 두 가지 충돌 대응 (조회 방식까지)
- **체이닝**: 같은 버킷에 연결 리스트로 매단다. 조회는 그 버킷의 리스트를 훑어 Key가 같은 노드를 찾는다. 삭제가 쉽지만 포인터 메모리를 더 쓴다.
- **개방 주소법**: 충돌 시 규칙(선형·이차 탐사, 이중 해싱)대로 다음 빈 버킷을 찾아 넣는다. 연속 메모리라 캐시 효율이 좋지만, 삭제가 까다롭고 밀집 시 군집(clustering)으로 느려진다.

### 적재율(Load Factor)과 리해싱 (수치)
- 적재율 = 저장된 개수 / 버킷 개수. 통상 0.75를 넘으면 충돌이 급증한다.
- 넘으면 버킷 배열을 대략 2배로 늘리고 전체를 다시 배치(리해싱)한다. 이 순간 O(N)이 걸려 지연 스파이크가 생기므로, 조금씩 나눠 옮기는 점진적 리해싱을 쓴다.

### 최악은 왜 O(N)인가
- 해시 함수가 나쁘거나 공격으로 모든 Key가 한 버킷에 몰리면, 그 버킷이 사실상 연결 리스트가 돼 조회가 O(N)으로 떨어진다.
- 공격자가 일부러 같은 해시값 Key를 퍼붓는 Hash DoS가 이 원리를 악용한다. 방어는 실행마다 시드가 바뀌는 해시 함수(SipHash)다.

### 흔한 오해·주의점
- "해시는 항상 O(1)"은 평균의 이야기다. 최악은 O(N)이고, 순서 보장·범위 검색이 필요하면 해시가 아니라 정렬 트리(B-Tree)를 써야 한다.
- 자바 HashMap은 한 버킷의 노드가 8개를 넘으면 리스트를 트리로 바꿔 최악을 O(log N)으로 방어한다.

## 연결 개념
- 암호학적 해시 (SHA-256 등) 
- 충돌 해결 기법 (Collision Resolution)
- 딕셔너리, Map 자료구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 해시 함수를 통해 임의 길이의 Key를 고정된 인덱스 배열 주소로 즉시 매핑하여 조회를 달성하는 자료구조이다.
> 2. **가치**: 캐시 시스템 등 대규모 키-값 분산 저장소에서 트래픽 병목을 제거하는 최상위 인프라 기반이다.
> 3. **판단 포인트**: 적재율(Load Factor) 관리와 충돌 방어 로직 설계 완성도에 성능이 의존한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| O(1) 조회의 근본 메커니즘 확인 | Key, Hash Function, Bucket Index 매핑 구조 | 충돌을 예외 상황으로 치부하고 누락 |
| 해시 충돌 해결 아키텍처 역량 | Chaining과 Open Addressing 원리 차이 | 특정 충돌 기법 하나만 서술하고 Trade-off 미제시 |

> 요약: 해시 테이블은 충돌이 불가피하므로, 충돌 대응 메커니즘과 동적 확장을 어떻게 제어할 것인지가 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: Key 값을 해시 함수로 연산해 버킷의 인덱스로 직접 매핑하는 키-값 형태의 자료구조
- 배경: 데이터베이스 인덱스의 트리 구조 조회 지연도 수용할 수 없는 초당 수백만 건의 매칭 환경 도래
- 필요성: Redis 캐시 등에서 데이터 볼륨(N) 증가와 무관하게 일관된 밀리초 이하 응답시간을 보장하기 위해 적용

---

## Ⅱ. 구조 및 구성요소

```text
Key 입력 -> 해시 함수 -> Hash Code 생성 -> Modulo 연산 -> Bucket 인덱스 매핑 -> 충돌 시 대응(Chaining 등) 
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 키 (Key) | 찾고자 하는 데이터의 고유 식별자 | 가변 길이 입력 가능 |
| 해시 함수 | Key를 고정 길이의 정수 해시 코드로 변환 | 균등 분포 보장이 성능의 핵심 |
| 버킷 (Bucket) | 인덱스 위치에 Value를 저장하는 배열 공간 | 여유 공간 확보 필수 |
| 충돌 (Collision) | 서로 다른 Key가 동일 버킷 인덱스로 매핑되는 현상 | 100% 방지 불가, 우회 로직 필요 |

> 요약: 해시 테이블은 탐색 속도를 함수 연산 비용으로 교환한 구조다.

---

## Ⅲ. 동작원리 및 해시 충돌 해결 흐름도

```text
Key 입력 -> 인덱스(i) 매핑 -> 버킷 검사 -> 비어있음: 정상 저장
                               |-> 사용 중: 기법 A (i 버킷에 노드 추가 - Chaining)
                                        : 기법 B (i+1 탐색 후 저장 - Open Addressing)
```

| 기법 구분 | 처리 방식 | 특징 및 장단점 |
|:---:|:---|:---|
| Chaining | 충돌 발생 슬롯에 연결 리스트 노드를 동적 추가 | 삭제가 용이하나 추가 포인터 메모리 필요 |
| Open Addressing - 선형 탐사 | 충돌 시 빈 버킷이 나올 때까지 인접 인덱스 순차 검사 | 군집화 리스크 발생, 밀집 시 성능 저하 극심 |
| Open Addressing - 이차 탐사 | 충돌 횟수의 제곱(1, 4, 9)만큼 건너뛰며 검사 | 1차 군집화는 방어하나, 동일 해시값의 2차 군집화 잔존 |
| Open Addressing - 이중 해싱 | 충돌 시 제2의 해시 함수를 적용해 이동 보폭 결정 | 군집화 리스크가 가장 적으나 연산 오버헤드 증가 |

> 요약: 데이터 분포 예측이 어려울 때 안정적인 Chaining 구조를 주로 채택하며, 극도의 캐시 지역성이 필요할 때만 개방 주소법을 쓴다.

---

## Ⅳ. 특징

| 구분 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 (Red-Black Tree 등) | 판단 포인트 |
|:---|:---|:---|:---|
| 평균 조회 성능 | O(1) | O(log N) | 순수 조회 성능이 최우선인지 |
| 순서 보장 | 키 순서 보장 안 함(임의 순서) | 키 정렬 순서 유지, 범위 검색(Range Query) 가능 | 정렬된 순회·범위 조회 필요 여부 |
| 최악 성능 | 충돌 심화 시 O(N)까지 저하 가능 | 자가 균형으로 항상 O(log N) 보장 | 최악 성능 보장이 필요한 실시간 시스템 여부 |

> 요약: 순수 키 조회 성능은 해시 테이블이 우세하나, 정렬 순회·범위 검색·최악 성능 보장이 필요하면 균형 이진 탐색 트리를 선택한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Chaining 방식 | Open Addressing 방식 | 선택 기준 |
|:---|:---|:---|:---|
| 메모리 구조 | 동적 노드 부하 | 고정된 배열 내 이동 처리 | 단편화 허용 여부 |
| 데이터 삭제 | 연결 끊기로 직관적/빠름 | 빈자리 마킹 처리 복잡 | 빈번한 삭제 발생 여부 |
| 캐시 적중률 | 노드 파편화로 캐시 효율 저하 | 연속 메모리로 히트율 높음 | 데이터 규모 제약 |

> 요약: 메모리가 풍부하고 삭제가 잦은 애플리케이션은 체이닝을, 잦은 삽입 탐색 시 캐시 성능이 중요하면 개방 주소법을 채택한다.

**주요 리스크·대응:**
- 해시 충돌 공격(Hash DoS): 공격자가 동일 해시값을 유도하는 키를 대량 삽입해 O(N)을 유발 → 랜덤 시드 해시 함수(SipHash) 적용 (지표: 단일 버킷 최대 체인 길이)
- 리해싱 지연 스파이크: 적재율 임계 초과로 전체 배열 재배치 발생 → 점진적 리해싱(Incremental Rehashing) (지표: 리해싱 구간 p99 지연)
- 특정 버킷 과밀: 해시 함수의 균등 분포 실패 → 해시 함수 품질 검증·솔트(Salt) 추가 (지표: 버킷별 적재 편차)

**적재율(Load Factor) 관리:**
- Load Factor = 저장된 데이터 수 / 전체 버킷 수. 통상 0.7~0.75를 넘으면 충돌이 급증함
- 임계치를 넘으면 배열을 확장(리해싱)하되, 점진적 리해싱으로 재배치 지연을 여러 연산에 분산함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 인덱스 보완 적용: MemoryDB에서 동등 조건 검색 시 Hash Index를 적용하여 조회 지연 완전 제거
2. 하이브리드 체이닝 최적화: 버킷에 노드가 8개를 초과하면 연결 리스트를 레드-블랙 트리로 변환하여 방어
3. 일관된 해싱 분산: 분산 서버 환경에서 서버 증설 시 전체 재해싱을 막기 위해 해시링 기법 적용, 데이터 이동 분산 통제

**결론 (2줄):**
- 기술사 판단: 해시 테이블은 O(1)을 보장하기 위해 버킷 팽창 비용을 미리 메모리에 지불하는 공간 기반 시간 최적화의 정점이다.
- 향후 방향: 단일 시스템 자료구조를 넘어 대규모 분산 아키텍처의 분산 노드 일관된 해싱 라우팅 등 필수 알고리즘으로 진화하였다.
