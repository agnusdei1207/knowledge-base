# 해시 테이블 (Hash Table)

## 1. 정의 및 개념

해시 테이블은 키(Key)를 해시 함수(Hash Function)에 입력하여 버킷(Bucket) 또는 슬롯 위치로 매핑하고, 해당 위치에 값을 저장하거나 조회하는 키-값 기반 자료구조이다.

| 구분 | 정의 | 핵심 역할 |
|---|---|---|
| **키(Key)** | 값을 찾기 위한 식별자 | 검색 기준 |
| **해시 함수** | 키를 정수 해시값 또는 버킷 인덱스로 변환 | 저장 위치 결정 |
| **버킷(Bucket)** | 해시 결과가 가리키는 저장 위치 | 데이터 저장 |
| **충돌(Collision)** | 서로 다른 키가 같은 버킷으로 매핑되는 현상 | 성능 저하 요인 |
| **적재율(Load Factor)** | 저장 원소 수 / 버킷 수 | 리사이즈 기준 |

평균적으로 삽입·검색·삭제가 `O(1)`이지만, 충돌이 집중되면 최악의 경우 `O(n)`까지 성능이 저하될 수 있다.

## 2. 구조 및 주요 연산

```text
Key -> Hash Function -> Bucket Index -> Collision Handling -> Value
```

**주요 연산**
- insert(key, value): 키를 해시하여 버킷에 저장
- search(key): 해시 위치에서 키 일치 여부 확인 후 값 반환
- delete(key): 해당 키의 엔트리 제거
- resize/rehash: 적재율 증가 시 버킷 수 확장 및 재배치

## 3. 충돌 처리 방식

| 방식 | 원리 | 장점 | 단점 |
|---|---|---|---|
| **체이닝(Chaining)** | 같은 버킷의 원소를 리스트·트리로 연결 | 삭제 단순, 적재율 유연 | 포인터 오버헤드, 캐시 효율 저하 |
| **개방 주소법(Open Addressing)** | 충돌 시 다른 빈 슬롯을 탐사 | 배열 기반, 캐시 친화적 | 탐사 길이 증가, 삭제 표시 필요 |
| **재해싱(Rehashing)** | 해시 함수 또는 버킷 수를 바꿔 재배치 | 분포 개선 | 전체 재배치 비용 발생 |

개방 주소법에는 선형 탐사, 이차 탐사, 이중 해싱 등이 있으며, 군집화(Clustering) 문제를 고려해야 한다.

## 4. 자료구조 비교

| 구분 | 배열/리스트 | 균형 트리 | 해시 테이블 |
|---|---:|---:|---:|
| 동등 검색 | `O(n)` | `O(log n)` | 평균 `O(1)` |
| 범위 검색 | 정렬 시 가능 | 우수 | 기본적으로 부적합 |
| 정렬 순회 | 별도 정렬 필요 | 가능 | 보장하지 않음 |
| 삽입·삭제 | 위치 탐색 필요 | 균형 유지 필요 | 평균 `O(1)` |
| 주요 용도 | 소규모 데이터 | 범위 질의·정렬 출력 | 캐시, 세션, 딕셔너리, 중복 검사 |

해시 테이블은 동등 검색에는 강하지만, 키 순서가 필요한 질의에는 트리나 정렬 인덱스가 더 적합하다.

## 5. 심화 이슈 (기술사 포인트)

1. **평균 `O(1)` 조건**
   - 해시 함수가 균등하게 분포하고 적재율이 관리될 때만 평균 `O(1)`이 성립한다.

2. **해시 충돌**
   - 충돌이 집중되면 체인 길이 또는 탐사 길이가 증가하여 성능이 급격히 저하된다.

3. **리사이즈 비용**
   - 버킷 확장 시 전체 원소 재해싱이 필요하여 순간 지연과 메모리 피크가 발생할 수 있다.

4. **해시 플러딩 공격**
   - 외부 입력 키가 특정 버킷에 몰리도록 조작될 수 있어 시드 랜덤화나 방어적 해시가 필요하다.

5. **분산 해시**
   - 분산 캐시나 샤딩 환경에서는 일관 해싱(Consistent Hashing)으로 노드 추가·제거 시 재배치 비용을 줄인다.

## 6. 결론

해시 테이블은 키 기반 동등 검색에서 매우 효율적인 자료구조이다. 다만 기술사 답안에서는 평균 `O(1)`만 강조하지 말고 해시 함수 품질, 충돌 처리, 적재율, 리사이즈, 범위 질의 한계까지 포함해 트리 구조와 비교해야 한다.
