## 미리 알고가기

- 해시 함수: 키를 고정 길이 해시값으로 변환하고, 이를 버킷 인덱스 계산에 사용하는 함수임
- 충돌(Collision): 서로 다른 두 개의 키가 해시 함수를 거친 후 동일한 버킷 인덱스로 매핑되는 현상임
- 버킷(Bucket): 해시 테이블 내부에서 데이터가 실제로 저장되는 개별 슬롯 또는 메모리 공간임
- 적재율(Load Factor): 전체 버킷 개수 대비 현재 저장된 원소 수의 비율로, 성능 저하와 확장 시점의 지표임

## Ⅰ. 개요

- **정의/개념**: 해시 테이블은 키(Key)를 해시 함수로 변환해 계산한 버킷 인덱스를 기준으로 값을 저장·조회하는 키-값(Key-Value) 기반 자료구조임
- **배경/필요성**: 대용량 세션 관리, 캐싱, 중복 검사 등에서 $O(\log n)$ 트리 검색보다 빠른 즉각적 조회가 요구되므로, 메모리 공간을 소모하는 대신 탐색 시간을 평균 $O(1)$로 단축할 구조가 필요함

## Ⅱ. 특징

- 해시 함수가 키를 고르게 분산하고 적재율이 관리되면 삽입·삭제·조회가 평균 $O(1)$로 수행되어 단건 키 조회에 적합함
- 해시 충돌이 특정 버킷에 집중될 경우 내부적으로 연결 리스트나 트리 탐색 비용이 추가되어 최악의 경우 성능이 $O(n)$으로 퇴화할 수 있음
- 데이터가 함수에 의해 분산 배치되므로 키 간의 선후 관계가 사라져 범위 질의(Range Query)나 정렬된 순회에는 부적합함

## Ⅲ. 종류 및 비교

| 판단 기준 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 (AVL/RB) | 정렬 배열 (Sorted Array) |
|:---|:---|:---|:---|
| **조회 성능** | 평균 $O(1)$ / 최악 $O(n)$ | 평균·최악 $O(\log n)$ | $O(\log n)$ (이진탐색) |
| **순서 보전** | 불가 (무작위 분산) | 가능 (중위 순회) | 가능 (인덱스 순차) |
| **갱신 비용** | 평균 $O(1)$, 재해싱 시 순간 비용 발생 | 회전·재색칠로 $O(\log n)$ 유지 | 삽입·삭제 시 데이터 이동 비용 큼 |
| **주요 용도** | 단건 조회, 캐시, 중복체크 | 범위 검색, 데이터 정렬 유지 | 읽기 전용 참조 데이터 |

> 요약: 단일 키 기반 조회가 목적이면 해시 테이블이 유리하며, 범위 검색이나 정렬된 순회가 필요하면 균형 트리나 정렬 배열을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 해시 함수 | 키를 버킷 인덱스로 변환하는 핵심 로직이며, 키 분포를 고르게 만들어 특정 버킷 집중을 줄여야 함 |
| 버킷/슬롯 | 데이터(또는 데이터의 포인터)를 실제로 보관하는 배열 형태의 저장 공간임 |
| 충돌 해결 구조 | 동일 버킷 매핑 시 연결 리스트로 잇는 체이닝(Chaining)이나 다른 빈 칸을 찾는 개방 주소법(Open Addressing)을 사용함 |
| 재해싱 정책 | 적재율 임계치 도달 시 버킷 크기를 확장하고 모든 키를 다시 배치하여 성능 저하를 방지하는 메커니즘임 |

```text
[ 해시 처리 구조 ]
+-----+      +---------------+      +--------------+      +--------------+
| Key | ---> | Hash Function | ---> | Bucket Index | ---> | Bucket Array |
+-----+      +---------------+      +--------------+      +--------------+
                                                          |
                                                          v
                                                  Value / Collision Chain
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 해시값 생성  | --> | 인덱스 매핑   | --> | 충돌 여부 확인 | --> | 데이터 입출력 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **해시 생성** — 입력 키를 해시 함수에 넣어 버킷 계산에 사용할 해시값을 산출함
2. **인덱스 매핑** — 해시값을 버킷 수로 나눈 나머지 등으로 배열 인덱스 범위에 매핑함
3. **충돌 확인** — 같은 인덱스에 다른 키가 존재하면 체이닝 또는 탐사 순서에 따라 후보 위치를 찾음
4. **입출력** — 저장 시에는 확정된 위치에 키와 값을 함께 보관하고, 조회 시에는 저장된 키와 요청 키의 일치 여부를 확인해 값을 반환함

## Ⅵ. 실무 적용 및 유의점

1. 외부 입력 키가 많은 웹 요청 맵에서는 HashDoS로 체인 길이가 늘어날 수 있으므로 시드 기반 해시 랜덤화와 체인 트리화를 적용하고 최대 체인 길이와 p99 조회 지연으로 방어 효과를 확인해야 함
2. 초기 버킷 크기가 작으면 빈번한 재해싱($Rehashing$)으로 순간 지연이 커질 수 있으므로, 예상 데이터 규모에 맞춰 초기 용량과 적재율 임계치를 정하고 재해싱 횟수와 p99 갱신 지연으로 확인해야 함

## Ⅶ. 결론

- 해시 테이블은 순서보다 단건 키 조회가 중요한 업무에서 평균 조회 시간을 낮추는 구조이므로, 해시 함수 분산도와 충돌 처리와 적재율을 함께 관리할 때 효과적으로 적용할 수 있음
