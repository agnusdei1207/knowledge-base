## 미리 알고가기

- 해시 함수: 키를 해시값으로 바꿔 버킷 인덱스를 계산하는 함수임
- 충돌(Collision): 서로 다른 키가 같은 버킷 인덱스로 매핑되는 현상임
- 버킷(Bucket): 키·값 또는 포인터가 저장되는 배열 슬롯임
- 적재율(Load Factor): 버킷 수 대비 원소 수의 비율이며 확장 시점 판단 지표임

## Ⅰ. 개요

- **정의/개념**: 해시 테이블은 해시 함수로 키의 버킷 위치를 계산해 값을 저장·조회하는 자료구조임
- **배경/필요성**: 세션·캐시·중복 검사는 단건 조회 지연이 중요하므로 메모리를 더 써 평균 조회를 $O(1)$로 낮추는 구조가 필요함

## Ⅱ. 특징

- 키가 고르게 분산되고 적재율이 낮으면 삽입·삭제·조회가 평균 $O(1)$임
- 충돌이 특정 버킷에 몰리면 최악 $O(n)$까지 퇴화함
- 키 순서가 사라져 범위 질의와 정렬 순회에는 부적합함

## Ⅲ. 종류 및 비교

| 판단 기준 | 해시 테이블 (Hash Table) | 균형 이진 탐색 트리 (AVL/RB) | 정렬 배열 (Sorted Array) |
|:---|:---|:---|:---|
| **조회 성능** | 평균 $O(1)$ / 최악 $O(n)$ | 평균·최악 $O(\log n)$ | $O(\log n)$ (이진탐색) |
| **순서 보전** | 불가, 버킷에 분산 | 가능, 중위 순회 사용 | 가능, 인덱스 순차 접근 |
| **갱신 비용** | 평균 $O(1)$, 재해싱 순간 비용 | 회전·재색칠로 $O(\log n)$ 유지 | 삽입·삭제 시 데이터 이동 큼 |
| **주요 용도** | 단건 조회, 캐시, 중복 검사 | 범위 검색, 정렬 유지 | 읽기 전용 참조 데이터 |

> 요약: 단건 키 조회는 해시 테이블, 범위 검색은 균형 트리, 읽기 전용 정렬 조회는 정렬 배열이 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 해시 함수 | 키를 버킷 인덱스로 변환하고 특정 버킷 집중을 줄임 |
| 버킷/슬롯 | 키·값 또는 포인터를 보관하는 배열 저장 공간임 |
| 충돌 해결 구조 | 동일 인덱스 충돌을 체이닝 또는 개방 주소법으로 처리함 |
| 재해싱 정책 | 적재율 임계치 도달 시 버킷을 확장하고 키를 다시 배치함 |

```text
[ 해시 처리 구조 ]
+-----+      +---------------+      +--------------+      +--------------+
| Key | ---> | Hash Function | ---> | Bucket Index | ---> | Bucket Array |
+-----+      +---------------+      +--------------+      +--------------+
                                                          |
                                                          v
                                                  Value / Collision Chain
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 해시값 생성  | --> | 인덱스 매핑   | --> | 충돌 여부 확인 | --> | 데이터 입출력 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **해시 생성** — 입력 키로 버킷 계산용 해시값을 산출함
2. **인덱스 매핑** — 해시값을 배열 인덱스 범위에 맞춤
3. **충돌 확인** — 같은 인덱스에 다른 키가 있으면 체인 또는 탐사 순서로 찾음
4. **입출력** — 저장은 키·값을 함께 보관하고, 조회는 키 일치 후 값을 반환함

## Ⅵ. 실무 적용 및 유의점

1. 웹 요청 맵은 HashDoS 대비로 해시 랜덤화·체인 트리화를 적용하고 p99 지연을 확인함
2. 초기 버킷은 예상 원소 수로 잡고 재해싱 횟수·p99 갱신 지연으로 검증함

## Ⅶ. 결론

- 해시 테이블은 단건 조회 지연을 낮추는 구조이므로 해시 분산도·충돌·적재율 관리가 필요함

## 작성 근거(검토용)

- **개요 구성**: 키를 버킷 위치로 바꾸는 구조를 정의해 평균 $O(1)$의 원인을 드러냄
- **특징 선정**: 분산, 충돌, 순서 손실은 해시 테이블의 성능과 적용 범위를 결정함
- **Ⅲ 비교축**: 균형 트리와 정렬 배열을 함께 둬 단건 조회·범위 검색·읽기 전용 조회를 구분함
- **구조 도식**: 키에서 해시 함수, 버킷 인덱스, 충돌 구조로 이어지는 저장 경로를 보이기 위해 배치함
- **실무 유의점**: HashDoS와 재해싱은 평균 성능이 무너지는 대표 조건이라 p99 지연으로 연결함
