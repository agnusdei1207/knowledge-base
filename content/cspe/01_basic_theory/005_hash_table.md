## Ⅰ. 개요
- **정의**: 키를 해시 함수로 변환하여 버킷 인덱스에 직접 매핑함으로써 평균 `O(1)` 탐색을 제공하는 자료구조
- **배경/필요성**: 정렬 기반 탐색 `O(log n)`(004 참조)보다 빠른 상수 시간 접근이 필요한 대량 키-값 저장 요구가 존재함
- **비유**: 사물함에 이름표(키)를 붙여 번호(해시값)로 즉시 찾아가는 방식과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해시 구조와 충돌 해결 이해 | 해시 함수 → 버킷 매핑, 충돌 해결 2가지 | 최악 O(n) 퇴화 조건과 로드 팩터 관계 |

> 요약: 키를 해시 함수로 인덱스에 매핑하여 평균 상수 시간에 데이터를 접근하는 자료구조임

## Ⅱ. 구성요소
```text
  Key --> 해시 함수 --> 버킷 인덱스 --> 버킷 배열
                                        |
                          +--------------+--------------+
                          |                             |
                     체이닝(Chaining)           오픈 어드레싱(Open Addressing)
                     연결 리스트 저장            선형/이차/이중 해싱 탐사
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 해시 함수 | 임의 크기의 키를 고정 범위 정수로 변환하는 함수 | 이름을 사물함 번호로 바꾸는 규칙 |
| 버킷 배열 | 해시값을 인덱스로 사용하는 고정 크기 배열 | 번호가 매겨진 사물함 행 |
| 체이닝 | 동일 버킷에 연결 리스트를 두어 충돌 항목을 순차 저장 | 같은 사물함 안에 서류를 겹쳐 넣는 것 |
| 오픈 어드레싱 | 충돌 시 다음 빈 버킷을 탐사하여 저장(선형/이차/이중 해싱) | 사물함이 차면 옆 빈 칸을 찾아 넣는 것 |
| 로드 팩터 | 저장 항목 수 / 버킷 수 비율, 충돌 빈도와 성능에 영향 | 사물함 행의 점유율 |

> 요약: 해시 함수·버킷 배열·충돌 해결 전략·로드 팩터가 해시 테이블의 핵심 구성임

## Ⅲ. 절차
```text
  키 입력            해시값 계산        버킷 접근          충돌 처리
  (key 수신)        (hash(key))       (index 매핑)      (체이닝/탐사)
   |                 |                 |                 |
   +----입력-------->+----계산-------->+----접근-------->+
  임의 타입 키      정수 인덱스 산출   배열 직접 접근     빈 슬롯 확보/탐색
```
- 1단계: 저장 또는 조회할 키를 입력받음
- 2단계: 해시 함수를 적용하여 키를 정수 인덱스로 변환함 — `index = hash(key) % bucket_size`
- 3단계: 산출된 인덱스로 버킷 배열에 직접 접근함 — 충돌이 없으면 즉시 저장 또는 반환
- 4단계: 충돌 발생 시 체이닝(연결 리스트 추가) 또는 오픈 어드레싱(다음 빈 슬롯 탐사)으로 처리함

> 요약: 키 입력 → 해시값 계산 → 버킷 접근 → 충돌 처리의 4단계로 데이터를 저장·조회함

## Ⅳ. 문제점
- 해시 충돌 퇴화: 해시 함수 품질이 낮으면 특정 버킷에 항목이 집중되어 탐색이 `O(n)`으로 퇴화함
- 메모리 낭비: 로드 팩터를 낮게 유지하면 빈 버킷이 많아져 메모리 활용률이 저하됨
- 순서 미보장: 삽입 순서나 키 순서가 유지되지 않아 범위 질의나 정렬 기반 연산을 지원하지 못함

> 요약: 충돌 퇴화, 메모리 비효율, 순서 미보장이 해시 테이블의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 균등 분포 특성이 검증된 해시 함수(MurmurHash, xxHash 등)를 적용하여 충돌 집중을 완화함
2. 중기: 로드 팩터 임계값(0.7~0.75) 도달 시 동적 리사이징(배열 2배 확장 + 재해싱)을 수행하여 메모리 활용과 성능을 균형 유지함
3. 장기: 순서 보장이 필요한 경우 해시 테이블과 연결 리스트를 결합한 LinkedHashMap 구조 또는 균형 트리 기반 맵을 병용함

> 요약: 해시 함수 개선, 동적 리사이징, 순서 보장 자료구조 병용으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 일관된 해싱(Consistent Hashing)이 분산 시스템 파티셔닝에 확대 적용되며, 병렬 해시맵이 멀티코어 환경에서 활용됨
- 기술사적 판단: `O(1)` 접근은 캐시, DB 인덱스, 라우팅 테이블 등 실시간 처리 핵심 기반임
- 기술사 제언: 충돌 해결 전략과 로드 팩터 설계를 데이터 특성에 맞게 선택하는 근거 제시가 필요
