## 미리 알고가기

- 키-값: 검색 기준인 키와 저장 대상인 값을 한 쌍으로 다루는 자료 표현임
- 해시 함수: 키를 고정 범위의 버킷 인덱스로 변환하는 함수임
- 버킷: 해시 결과가 가리키는 저장 위치 또는 저장 슬롯 집합임
- 충돌: 서로 다른 키가 같은 버킷으로 매핑되는 현상임
- 적재율(load factor): 저장된 원소 수를 버킷 수로 나눈 값이며 평균 `O(1)` 가정을 지탱하는 핵심 지표임

## Ⅰ. 개요

- **정의**: 해시 테이블은 키를 해시 함수로 버킷에 매핑해 삽입·검색·삭제 비용을 평균 `O(1)`로 낮추는 키-값 자료구조임
- **배경/필요성**: 배열·트리 검색은 원소를 하나씩 비교하며 `O(n)`~`O(log n)` 비용이 쌓이므로, 키를 저장 위치로 직접 변환해 비교 없이 접근하는 구조가 필요해짐. 다만 평균 `O(1)`은 해시 분포가 균등할 때의 값이고 최악은 `O(n)`이며 정렬 순서를 보존하지 않으므로, 범위·정렬 질의가 핵심이면 트리·정렬 인덱스와 구분해 선택해야 함.
- **비유**: 이름을 사물함 번호로 바꿔 바로 찾아가되, 같은 번호가 나오면 사물함 안에서 추가 규칙으로 찾는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 키 기반 자료구조 선택 역량 확인 | 해시 함수, 버킷, 충돌, 적재율, 평균 `O(1)` | 충돌 비용 누락, 순서 질의 오해 |

> 요약: 해시 테이블은 키를 위치로 변환해 평균 `O(1)` 동등 검색을 제공하지만, 충돌 처리와 적재율 관리가 실제 성능을 좌우함.

## Ⅱ. 특징/비교

| 판단 기준 | 배열/리스트 검색 | 균형 트리 | 해시 테이블 |
|:---|:---|:---|:---|
| 동등 검색 비용 | 보통 `O(n)` | `O(log n)` | 평균 `O(1)` |
| 순서 질의 | 배열 정렬 시 가능 | 범위·순회에 강함 | 기본 구조는 약함 |
| 삽입/삭제 | 위치 탐색과 이동 비용 발생 | 균형 유지 비용 발생 | 평균 `O(1)`이나 적재율 초과 시 리사이즈 비용 |
| 성능 조건 | 데이터 작거나 단순할 때 | 정렬 순서 유지가 필요할 때 | 해시 분포와 적재율이 관리될 때 |
| 선택 기준 | 소규모, 순차 처리 | 범위 검색, 정렬 출력 | 캐시, 세션, 딕셔너리, 중복 검사 |

> 요약: 해시 테이블은 순서가 아니라 키 존재 여부와 값 접근이 핵심인 업무에서 선택하는 자료구조임.

- 암호학적 해시는 역상·충돌 저항성이 목적이고, 자료구조용 해시는 낮은 계산 비용과 버킷 균등 분포가 목적이라 요구 조건이 서로 다름
- 충돌 처리는 체이닝(separate chaining), 개방 주소법(open addressing), 재해싱(rehashing)으로 나뉘며 메모리 사용과 캐시 적중 특성이 서로 다름
- 적재율이 높아지면 평균 `O(1)` 가정이 약해져 리사이즈 정책이 필수임

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| 입력 키  | ---> | 해시함수 | ---> | 버킷     |
+----------+      +----------+      +----------+
      |                 |                 |
      v                 v                 v
+----------+      +----------+      +----------+
| 값       |      | 충돌처리 |      | 저장/조회|
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 키 | 값을 찾기 위한 식별자이며 동등성 비교가 가능해야 함 | 이름표 |
| 해시 함수 | 키를 정수 해시값과 버킷 인덱스로 변환함 | 사물함 번호 계산기 |
| 버킷 배열 | 해시 결과가 접근하는 기본 저장 공간임 | 사물함 줄 |
| 충돌 처리 | 같은 버킷에 여러 키가 모일 때 체인이나 탐사로 실제 위치를 결정함 | 같은 번호 안의 칸 구분 |
| 리사이즈 정책 | 적재율이 임계값을 넘으면 버킷 수를 늘리고 재배치함 | 사물함 증설 |

> 요약: 해시 테이블은 키 변환, 버킷 저장, 충돌 해결, 적재율 조정이 결합된 평균 `O(1)` 접근 구조임.

- 키의 동등성 비교와 해시값 계산 규칙은 반드시 일관되어야 함
- 체이닝은 노드 포인터 메모리가 늘지만 삭제가 단순하고, 개방 주소법은 연속 배열이라 캐시 적중률이 높지만 탐사 길이와 삭제 표시 관리가 필요함
- 리사이즈는 모든 원소 재해싱을 유발할 수 있어 지연 시간 스파이크를 만들 수 있음

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| 키수신   | ---> | 해시계산 | ---> | 버킷접근 | ---> | 충돌처리 |
+----------+      +----------+      +----------+      +----------+
                                                            |
                                                            v
                                                      +----------+
                                                      | 결과반환 |
                                                      +----------+
```

1. **입력/요구 식별** - 키 타입, 동등성 기준, 삽입·조회·삭제 비율, 순서 질의 필요성을 확인함
2. **해시 계산** - 키의 해시값을 계산하고 버킷 수에 맞춰 인덱스를 산출함
3. **버킷 처리** - 삽입은 빈 위치나 체인에 저장하고, 조회·삭제는 키 동등성으로 실제 원소를 확인함
4. **검증/조정** - 충돌 횟수와 적재율을 확인해 리사이즈, 해시 함수 교체, 버킷 수 조정을 수행함

> 요약: 해시 테이블 절차는 키를 버킷으로 빠르게 이동시킨 뒤 충돌을 해결하고 적재율로 성능을 통제하는 흐름임.

- 개방 주소법은 삭제 슬롯을 빈칸으로 두면 탐사 경로가 끊기므로, 삭제 표시(tombstone)로 경로를 보존해야 함
- 동시성 환경에서는 버킷 단위 잠금, 락 프리(lock-free) 구조, 샤딩으로 경합을 줄여야 함
- 외부 입력 키가 같은 버킷에 몰리도록 조작되는 해시 플러딩(hash flooding) 공격에는 시드 랜덤화 해시로 방어해야 함

## Ⅴ. 문제점

- **P1 충돌 집중**: 해시 함수 분포가 나쁘거나 키 패턴이 치우치면 특정 버킷에 원소가 몰려 조회 비용이 `O(n)`에 가까워짐
- **P2 리사이즈 지연**: 적재율 임계값을 넘을 때 전체 원소 재배치가 발생해 순간 지연과 메모리 피크가 커질 수 있음
- **P3 순서 질의 부적합**: 기본 해시 테이블은 키의 정렬 순서를 보존하지 않아 범위 검색, 최소/최대 검색, 정렬 출력에서 전체 스캔이 필요할 수 있음

> 요약: 해시 테이블의 운영 리스크는 충돌, 리사이즈, 순서 질의 요구가 평균 `O(1)` 가정을 깨는 데 있음.

## Ⅵ. 개선방안

- **P1 대응**: 키 분포에 맞는 해시 함수를 선택하고 충돌 통계, 최대 체인 길이, 탐사 길이를 모니터링함 (확인: 버킷 분포 히스토그램)
- **P2 대응**: 적재율 임계값, 점진 리사이즈, 초기 용량 산정을 적용해 재해싱 비용을 분산함 (확인: 리사이즈 시 p99 지연)
- **P3 대응**: 범위 질의가 핵심이면 균형 트리, B-Tree, 정렬 배열 인덱스를 병행하거나 대체함 (확인: 범위 검색 응답시간)

> 요약: 해시 테이블 개선은 분포 품질과 용량 정책을 관리하고, 순서 요구는 적합한 자료구조로 분리하는 방식이 필요함.

## Ⅶ. 전망

- **발전 방향**: 인메모리 캐시, 분산 키-값 저장소, 언어 런타임 딕셔너리에서 해시 테이블은 계속 핵심 구조로 사용됨
- **기술사적 판단**: 평균 성능만 강조하지 말고 충돌 방어, 리사이즈 비용, 순서 질의 필요성을 기준으로 트리와 비교해야 함
- **기술사 제언**: 답안에서는 `해시 함수 -> 버킷 -> 충돌 처리 -> 적재율 관리` 흐름을 도식으로 제시하면 구조 판단이 명확해짐
