## Ⅰ. 개요
- **정의**: 키를 해시 함수로 인덱스에 매핑하여 평균 O(1) 접근을 제공하는 자료구조
- **배경/필요성**: 배열은 인덱스 접근은 O(1)이나 키 기반 탐색은 O(N)이므로, 키-값 쌍을 상수 시간에 처리할 매핑 구조가 필요함
- **비유**: 도서관 색인 카드처럼, 책 제목(키)으로 서가 번호(인덱스)를 즉시 찾는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해시 함수와 충돌 해결 원리 이해 | 체이닝 vs 개방 주소법 비교 | 최악 O(N) 퇴화 조건 누락 금지 |
| 적재율과 리해싱 관계 파악 | 적재율 임계값과 리해싱 트리거 | 해시 함수 균등 분포 조건 언급 필요 |

> 요약: 키를 해시 함수로 변환하여 버킷에 매핑하고, 충돌 해결 전략으로 평균 O(1) 연산을 보장하는 구조임

## Ⅱ. 구성요소
```text
  Key --> [Hash Function] --> Index --> [Bucket Array]
                                            |
                              +---------+---+---+---------+
                              | Slot 0  | Slot 1| Slot N  |
                              +---------+---+---+---------+
                                            |
                                            v
                                      (Collision Resolution)
                                       /            \
                              Chaining          Open Addressing
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 해시 함수 | 임의 크기 키를 고정 범위 정수로 변환하는 함수 | 학생 이름을 반 번호로 배정하는 규칙 |
| 버킷 배열 | 해시 값을 인덱스로 사용하는 고정 크기 배열 | 번호가 붙은 사물함 |
| 적재율 | 저장 항목 수 / 버킷 크기, 충돌 빈도의 지표 | 사물함 점유율 |
| 체이닝 | 같은 인덱스에 연결 리스트(006 참조)로 항목 연결 | 한 사물함에 꼬리표로 물건 연결 |
| 개방 주소법 | 충돌 시 다음 빈 슬롯을 탐색하여 저장 | 사물함이 차면 옆 빈 칸 사용 |

> 요약: 해시 함수, 버킷 배열, 충돌 해결 전략이 해시 테이블의 3대 구성요소임

## Ⅲ. 절차
```text
  Put(key, value)
      |
      v
  hash(key) % size --> index
      |
      v
  Bucket[index] 비어 있는가? --Yes--> 저장
      |
      No
      v
  충돌 해결(Chaining / Probing)
      |
      v
  적재율 > 임계값? --Yes--> 리해싱(배열 확장 + 재배치)
```
- 1단계: 키를 해시 함수에 입력하여 `hash(key) % size`로 인덱스 산출
- 2단계: 해당 버킷이 비어 있으면 키-값 쌍 저장, 이미 같은 키면 값 갱신
- 3단계: 버킷 충돌 시 체이닝(리스트 추가) 또는 개방 주소법(선형/이차/이중 해싱)으로 해결
- 4단계: 적재율이 임계값(통상 0.75)을 초과하면 배열을 2배 확장하고 전체 항목을 재해싱

> 요약: 해시 → 인덱스 산출 → 저장/충돌 해결 → 적재율 초과 시 리해싱 순서로 동작함

## Ⅳ. 문제점
- 해시 충돌 집중: 해시 함수 분포가 편향되면 특정 버킷에 항목이 집중되어 O(N) 탐색으로 퇴화함
- 리해싱 지연: 적재율 초과 시 전체 항목 재배치로 O(N) 일시 지연이 발생하여 실시간 처리에 부담됨
- 메모리 낭비: 충돌 대비로 버킷을 여유 있게 할당하면 미사용 슬롯이 증가하여 공간 효율이 저하됨

> 요약: 충돌 집중에 의한 성능 퇴화, 리해싱 지연, 미사용 슬롯에 의한 메모리 낭비가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 균등 분포 해시 함수(곱셈 해싱, MurmurHash 등) 적용으로 충돌 집중 완화
2. 중기: 점진적 리해싱(incremental rehashing) 도입으로 한 번에 전체 재배치하지 않고 분할 수행
3. 장기: 쿠쿠 해싱·로빈 후드 해싱 등 고급 개방 주소법으로 슬롯 활용률 극대화 및 메모리 효율 개선

> 요약: 해시 함수 개선, 점진적 리해싱, 고급 충돌 해결 기법으로 각 문제를 대응함

## Ⅵ. 전망
- 발전 방향: 캐시 친화적 해시맵(flat hash map) 설계가 CPU 캐시 적중률 향상을 위해 확산 중임
- 기술사적 판단: 분산 시스템의 일관적 해싱(consistent hashing)이 데이터 파티셔닝의 핵심 기법으로 자리잡음
- 기술사 제언: 해시 테이블 선택 시 적재율·충돌 해결 방식·메모리 오버헤드를 워크로드 특성에 맞게 결정할 필요가 있음
