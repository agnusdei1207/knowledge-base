## 미리 알고가기

- 해시 함수: 키를 버킷 인덱스로 바꾸는 함수임
- 버킷: 해시 결과가 가리키는 저장 위치임
- 충돌: 서로 다른 키가 같은 버킷으로 가는 현상임
- 적재율: 저장된 원소 수를 버킷 수로 나눈 값임

## Ⅰ. 개요

- **정의/개념**: 해시 테이블은 키를 해시 함수로 버킷 위치에 매핑해 값을 저장하고 찾는 자료구조임
- **배경/필요성**: 세션, 캐시, 중복 검사는 키로 즉시 찾는 일이 많음. 해시 테이블은 정렬 순서보다 빠른 일치 조회가 필요한 업무에 적합함

## Ⅱ. 특징

- 해시 함수로 위치를 바로 계산하므로 평균 조회와 삽입이 $O(1)$에 가까움
- 충돌이 많아지면 같은 버킷 안에서 다시 찾아야 하므로 성능이 떨어짐
- 키 순서를 보존하지 않으므로 범위 검색이나 정렬 순회에는 맞지 않음
- 버킷 확장과 재해싱은 순간 비용이 크므로 대량 삽입 구간에서는 용량 계획이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 해시 테이블 | 균형 트리 | 정렬 배열 |
|:---|:---|:---|:---|
| 조회 성능 | 평균 $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 최악 상황 | 충돌이 몰리면 $O(n)$ | 균형 유지 시 $O(\log n)$ | 조회는 안정적이나 갱신이 느림 |
| 순서 처리 | 순서 보존 약함 | 정렬 순회와 범위 검색 가능 | 정렬 순회와 범위 검색 가능 |
| 적합한 업무 | 캐시, 세션, 중복 검사 | 정렬 맵, 범위 인덱스 | 변경이 적은 조회용 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키와 값 | 키로 위치를 찾고 값은 해당 위치에 저장함 |
| 해시 함수 | 키를 고르게 흩어지게 해야 충돌이 줄어듦 |
| 버킷 배열 | 해시 결과가 가리키는 저장 공간들의 집합임 |
| 충돌 처리 | 체이닝이나 개방 주소법으로 같은 버킷의 여러 키를 처리함 |
| 재해싱 | 적재율이 높아질 때 버킷을 늘리고 기존 키를 다시 배치함 |

```text
+-----+     +-----------+     +--------+     +------+
| Key | --> | Hash func | --> | Bucket | --> | Value |
+-----+     +-----------+     +--------+     +------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 키 입력   | --> | 해시 계산 | --> | 버킷 접근 | --> | 값 비교/처리 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. 키의 해시 값을 계산함
2. 해시 값을 버킷 범위에 맞는 인덱스로 바꿈
3. 해당 버킷에서 키가 같은 원소를 찾음
4. 조회, 삽입, 삭제에 맞게 값을 처리함

## Ⅵ. 실무 적용 및 유의점

1. 외부 입력 키가 몰릴 수 있는 서비스에서는 해시 충돌률과 최악 조회 지연을 측정하고 필요하면 보안 해시나 트리 버킷을 검토해야 함
2. 범위 검색이 필요한 인덱스라면 해시 테이블보다 균형 트리나 B-Tree 계열을 선택해야 함

## Ⅶ. 결론

- 해시 테이블은 키 일치 조회에 강하지만, 충돌 관리와 순서 처리 한계를 함께 고려해야 안정적으로 쓸 수 있음
