# 📖 【암기용】 개념 완전 이해

> 목적: 해시 테이블을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 키를 해시값으로 변환해 배열 위치에 저장하는 자료구조
- **왜 필요한가**: 배열은 인덱스를 알 때 O(1)이지만 임의 키 조회에는 검색이 필요하다. 해시 테이블은 키를 배열 인덱스로 바꿔 평균 O(1) 조회·삽입·삭제를 제공한다.
- **핵심 직관**: 이름표를 숫자 사물함 번호로 바꿔 바로 찾아가는 구조임

## 깊이 이해
- **배경·문제의식**: 사용자 ID, 세션 토큰, 캐시 키처럼 값의 위치를 키로 찾아야 하는 시스템에서 선형 탐색 O(n)은 n 증가 시 요청 지연을 키운다.
- **작동 원리**: 해시 함수 h(key)가 키를 정수로 바꾸고, `index=h(key) mod m`으로 버킷을 정한다. 같은 인덱스가 나오면 체이닝 또는 개방 주소법으로 충돌을 처리한다.
- **비유**: 도서관에서 책 제목을 바로 서가 번호로 바꾸는 색인표와 같다. 같은 번호에 여러 책이 몰리면 보조 목록으로 구분한다.
- **구체 예시**: load factor α=0.75를 넘으면 버킷 수를 2배로 늘려 rehash 수행. 평균 탐색은 O(1), 모든 키가 한 버킷에 몰리면 최악 O(n).
- **흔한 오해·주의점**: 해시는 항상 O(1)이 아니다. 해시 함수 품질, 충돌 처리, 리사이징 정책, 공격 입력(HashDoS) 대응이 함께 필요함.

## 연결 개념
- 해시 함수 — 키 분포를 결정하는 핵심 구성
- 캐시·세션 저장소 — 해시 테이블의 대표 응용
- Bloom Filter — 해시 기반 확률적 멤버십 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 해시 테이블은 해시 함수로 키를 배열 인덱스에 매핑하여 평균 O(1) 접근을 달성하는 키-값 자료구조이다.
> 2. **가치**: 캐시, DB 해시 인덱스, 세션 저장소, 중복 제거에서 조회·삽입 비용을 선형 탐색 O(n)에서 평균 O(1)로 낮춘다.
> 3. **판단 포인트**: 해시 분포, 충돌 해결, load factor, rehash 비용, 동시성 제어, HashDoS 방어가 설계 기준이다.

## Ⅰ. 개요 및 필요성

개요: 키를 배열 위치로 변환하는 구조이다. 대규모 키-값 조회에서 순차 탐색은 n 증가에 따라 지연시간이 증가한다. 해시 테이블은 해시 함수와 충돌 처리로 평균 O(1) 조회를 제공해 캐시·인덱스·집합 연산의 기반이 됨.

## Ⅱ. 구조 및 구성요소

```text
┌────────┐   ┌────────────┐   ┌──────────┐
│  Key   │──▶│ Hash h(key)│──▶│ Bucket i │
└────────┘   └─────┬──────┘   └────┬─────┘
                   │               ▼
              mod m 연산     Chain / Open Address
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 해시 함수 | 키를 정수 해시값으로 변환 | 균등 분포·저충돌 필요 |
| 버킷 배열 | 해시값을 저장 위치로 매핑 | 크기 m, α=n/m |
| 충돌 처리 | 동일 버킷 키 저장 | 체이닝, 선형/이차 조사 |
| 리사이징 | α 임계치 초과 시 재배치 | α 0.75 전후 기준 |

> 요약: 해시 테이블은 해시 함수, 버킷 배열, 충돌 처리, 리사이징 정책이 함께 동작함.

## Ⅲ. 동작원리 및 흐름도

```text
put/get 요청 → h(key) 계산 → index = h mod m
            → 버킷 접근 → 충돌 탐색 → 값 반환/삽입
            → α 임계치 초과 시 rehash
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 키 입력 | null·타입·동등성 규칙 |
| 2 | 해시 계산 | 분포 편차, 충돌률 |
| 3 | 버킷 접근 | index 범위 0~m-1 |
| 4 | 충돌 처리 | chain 길이, probe 횟수 |
| 5 | 리사이징 | α>0.75, rehash 시간 |

> 요약: 키 입력 후 해시 인덱스로 버킷에 접근하고, 충돌과 load factor를 통제해 평균 접근 비용을 유지함.

## Ⅳ. 특징

| 구분 | 해시 테이블 | 균형 트리 | 수치 기준 |
|:---|:---|:---|:---|
| 조회 | 평균 O(1), 최악 O(n) | O(log n) | 충돌 적을 때 1~2회 접근 |
| 정렬 순회 | 별도 정렬 필요 | 중위 순회 O(n) | range query는 트리 유리 |
| 메모리 | 버킷 여유 공간 필요 | 포인터·색상 정보 필요 | α=0.75면 25% 이상 여유 |
| 보안 | HashDoS 입력 주의 | 비교 기반이라 충돌 공격 영향 낮음 | SipHash 등 랜덤 해시 |

> 요약: 해시 테이블은 단건 조회·삽입에 적합하고, 정렬·범위 질의는 균형 트리 또는 B-Tree가 적합함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 캐시·세션: TTL, LRU, shard key를 함께 설계해 평균 O(1) 조회와 메모리 상한을 동시에 관리
2. 충돌 제어: α 0.75 기준 리사이징, 체이닝 길이 임계치 8 이상이면 트리화(Java HashMap 방식) 검토
3. 보안·동시성: SipHash·난수 seed로 HashDoS 완화, lock striping 또는 concurrent hash map으로 경합 구간 축소

**결론 (2줄):**
- 기술사 판단: 단건 키 조회·중복 제거는 해시 테이블, 정렬 순회·범위 질의는 트리 인덱스를 선택함
- 향후 방향: 분산 해시 테이블과 consistent hashing으로 노드 증감 시 재배치 키 비율을 1/N 수준으로 낮추는 설계 필요
