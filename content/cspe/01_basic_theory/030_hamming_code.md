## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 데이터 비트에 패리티 비트를 추가하여 1비트 오류를 검출·정정(SEC)하고, 2비트 오류를 검출(DED)하는 오류 제어 코드임 |
| **배경/필요성** | 메모리·통신 채널에서 전기적 잡음·방사선에 의한 비트 반전 오류가 발생하며, 실시간 오류 정정이 필수임 |
| **출제 의도** | 해밍 코드의 패리티 비트 위치와 신드롬 계산을 통한 오류 정정 과정을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 데이터   | --> | 패리티   | --> | 코드워드  |
| 비트(D)  |     | 비트(P)  |     | (D+P)   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 데이터 비트(D) | 실제 전송할 원본 데이터 비트임 | 편지 내용 |
| 패리티 비트(P) | 2^i(1,2,4,8…) 위치에 삽입되어 특정 비트 그룹의 짝수/홀수 패리티를 검사함 | 검산용 체크 숫자 |
| 신드롬(Syndrome) | 수신 측에서 패리티를 재계산하여 오류 위치를 가리키는 이진값임 | 오류 위치 좌표 |

> 요약: 데이터에 패리티 비트를 삽입하고, 수신 시 신드롬 계산으로 오류 비트 위치를 정정함.

## Ⅲ. 절차
```
+------------+     +------------+
| 패리티위치  | --> | 패리티값   |
| 결정(2^i) |     | 계산       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 오류정정   | <-- | 신드롬    |
| (비트반전) |     | 계산       |
+------------+     +------------+
```

1. 패리티 위치 결정: 2^0=1, 2^1=2, 2^2=4… 위치에 패리티 비트를 배치하고 나머지에 데이터를 채움
2. 패리티 값 계산: 각 패리티 비트가 담당하는 비트 그룹의 XOR로 짝수 패리티를 설정함
3. 신드롬 계산: 수신 측에서 동일 그룹의 패리티를 재계산하여 신드롬 벡터를 구함
4. 오류 정정: 신드롬이 0이 아니면 해당 값이 오류 비트 위치이므로 비트를 반전하여 정정함

> 요약: 패리티 배치 → 계산 → 신드롬 → 정정으로 1비트 오류를 자동 정정함.

## Ⅳ. 문제점
- 1비트 한계: 기본 해밍 코드(SEC)는 1비트만 정정 가능하며, 2비트 이상 오류는 정정 불가함
- 오버헤드: 패리티 비트 추가로 데이터 효율(코드율)이 감소함(예: 7,4 해밍 → 코드율 4/7)
- 버스트 오류 미대응: 연속 비트 오류(Burst Error)에는 해밍 코드가 부적합함

## Ⅴ. 개선방안
- (단기) SECDED: 전체 패리티 비트를 1개 추가하여 2비트 검출(DED) 기능을 확보함
- (중기) Reed-Solomon: 버스트 오류 정정이 가능한 블록 코드를 적용함(CD/DVD·QR코드)
- (장기) LDPC·Turbo 코드: 섀넌 한계에 근접하는 현대적 오류 정정 코드를 적용함(5G·SSD)

## Ⅵ. 전망
- ECC DRAM에서 SECDED이 표준이며, 5G·위성통신에서 LDPC·Polar 코드가 채널 코딩의 핵심으로 자리잡을 전망임
