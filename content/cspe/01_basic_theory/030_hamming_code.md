## 미리 알고가기

- 오류 검출(Error Detection): 수신 데이터에 비트 오류가 있는지 찾아내는 기능임
- 오류 정정(Error Correction): 오류 위치를 찾아 원래 값으로 복구하는 기능임
- 패리티 비트(Parity Bit): 데이터 비트 일부를 검사하기 위해 추가하는 검사용 비트임
- 신드롬(Syndrome): 수신 후 패리티 검사를 다시 수행해 얻는 오류 위치 정보임
- 단일 오류 정정·이중 오류 검출(SECDED): 단일 비트 오류는 정정하고 이중 비트 오류는 검출하는 방식임
- 순환 중복 검사(CRC): 송수신 측이 같은 다항식으로 계산한 나머지를 비교해 연속 비트 오류를 검출하는 방식임
- $d$·$p$: 각각 데이터 비트 수와 패리티 비트 수이며 $D$·$P$는 도식의 개별 비트를 뜻함

## 작성 근거(검토용)

- **개요 구성**: 기출 키워드이므로 정의에서 패리티 위치, 신드롬, 단일 비트 정정을 한 문장에 포함함
- **Ⅱ. 특징 선정**: 위치 산출 원리·패리티 수 조건·SECDED 확장·버스트 오류 한계를 중심으로 선별함
- **Ⅲ. 비교축 선정**: 패리티·해밍·SECDED·CRC를 비교해 검출과 정정의 차이를 명확히 보이게 함
- **Ⅳ·Ⅴ. 구조·절차 선정**: 7비트 예시와 절차를 결합해 계산 문제와 서술형 답안을 모두 대비하게 함
- **Ⅵ·Ⅶ. 사례·결론 선정**: ECC 메모리와 네트워크 패킷처럼 정정 우선 환경과 검출 우선 환경을 구분함
- **전수 검수**: 제목부터 결론까지 용어·표·도식·요약을 대조하고 패리티 위치·신드롬 정의와 절 간 판단축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 해밍 코드는 코드워드의 2의 거듭제곱 위치에 패리티 비트를 삽입하고 신드롬으로 단일 비트 오류 위치를 찾아 정정하는 선형 블록 부호임
- **배경/필요성**: 메모리·내부 버스에서 재전송 없이 단일 비트 오류를 복구할 부호화가 필요함

### 쉽게 이해하기 (학습용)
- 물건을 겹치는 여러 그룹으로 나눠 세어보면 어느 그룹에서 개수가 안 맞는지 조합만으로 문제 위치를 짚어낼 수 있듯, 특정 자리마다 검사표(패리티)를 심어 오류난 자리를 스스로 찾아냄

## Ⅱ. 특징

- 여러 패리티 비트가 데이터 비트를 겹쳐 검사해 오류 위치를 이진수로 산출함
- 데이터 비트 $d$와 패리티 비트 $p$는 $2^p \geq d + p + 1$ 조건을 만족해야 함
- 기본 해밍 코드는 단일 비트 오류를 정정하고, 전체 패리티를 추가하면 SECDED가 됨
- 여러 비트가 동시에 바뀌면 신드롬이 실제 오류 위치를 가리키지 않을 수 있으므로 오류 패턴에 맞는 보완 기법이 필요함

### 쉽게 이해하기 (학습용)
- 서로 겹치는 여러 검사 그룹의 결과를 모으면 그 자체가 이진수 주소처럼 오류 위치를 가리키고, 검사표 하나를 더 추가하면 오류가 하나인지 둘인지까지 구별할 수 있음
- 다만 한꺼번에 여러 자리가 틀리면 이 조합 방식이 엉뚱한 자리를 가리킬 수 있음

## Ⅲ. 종류 및 비교

| 방식 | 검출 범위 | 정정 범위 | 부가 비트 |
|:---|:---|:---|:---|
| 단순 패리티 | 홀수 개 비트 오류 | 없음 | 패리티 1비트 |
| 해밍 코드 | 단일 비트 오류 | 단일 비트 오류 | 패리티 $p$비트 |
| SECDED | 단일·이중 비트 오류 | 단일 비트 오류 | 해밍 $p$비트 + 전체 패리티 1비트 |
| CRC | 생성 다항식이 보장하는 다중·버스트 오류 | 없음 | 생성 다항식 차수 비트 |

> 요약: 1비트 정정은 해밍 코드를, 다중·버스트 오류 검출은 생성 다항식에 맞는 CRC를 적용함.

### 쉽게 이해하기 (학습용)
- 단순 패리티는 개수가 홀수로 틀렸는지만 알려주는 경비원, 해밍 코드는 어디가 틀렸는지 짚어주는 경비원, SECDED는 둘 다 틀린 것까지 알아채는 경비원, CRC는 긴 구간 전체를 훑어 오류를 잡아내지만 고치지는 못하는 검사관임

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 데이터 비트($D$) | 2의 거듭제곱이 아닌 위치에 배치되는 원본 정보 비트 |
| 패리티 비트($P$) | 2의 거듭제곱 위치의 검사 비트 |
| 코드워드 | 데이터·패리티 결합 전송 단위 |
| 패리티 그룹 | 서로 겹치는 검사 위치 집합 |
| 신드롬 | 패리티 결과 기반 오류 위치값 |

```text
위치: 1  2  3  4  5  6  7
비트: P1 P2 D1 P4 D2 D3 D4

P1 검사: 1·3·5·7
P2 검사: 2·3·6·7
P4 검사: 4·5·6·7
```

> 요약: 해밍 코드는 겹치는 패리티 그룹을 검사해 신드롬을 만들고 오류 비트 위치를 결정함.

### 쉽게 이해하기 (학습용)
- 데이터 비트는 원래 전하려는 내용물, 패리티 비트는 곳곳에 심어둔 검사표, 패리티 그룹은 서로 겹치게 묶은 검사 범위, 신드롬은 그 검사표들을 다시 확인해 나온 오류 위치 힌트임

## Ⅴ. 원리 및 절차 흐름도

```text
데이터·패리티 비트 배치 → 코드워드 전송 → 신드롬 계산
                                          ├─ 0 → 오류 없음
                                          └─ 0 아님 → 해당 비트 반전
```

1. **패리티 배치**: 데이터 길이에 맞는 패리티 수를 정하고 2의 거듭제곱 위치에 둠
2. **코드워드 생성**: 각 패리티 그룹에서 1의 개수가 짝수 또는 홀수가 되도록 값을 채움
3. **신드롬 계산**: 수신 후 같은 그룹을 다시 검사해 실패한 패리티 위치를 모음
4. **오류 정정**: 신드롬이 0이면 정상이고, 0이 아니면 해당 위치 비트를 반전함

> 요약: 해밍 코드는 신드롬이 가리키는 단일 비트를 반전해 재전송 없이 오류를 복구함.

### 쉽게 이해하기 (학습용)
- 검사표를 정해진 자리에 심어 내용물을 완성하고, 도착한 뒤 같은 검사표를 다시 확인해 어긋난 곳을 모으면, 결과가 0이면 정상이고 아니면 그 위치의 비트를 뒤집어 고침

## Ⅵ. 실무 사례

1. ECC 메모리는 단일 비트 오류를 정정하고 메모리 스크러빙으로 누적 오류를 제거함
2. 캐시는 SECDED로 1비트 오류를 정정하고 2비트 오류를 검출함

### 쉽게 이해하기 (학습용)
- 컴퓨터 메모리가 스스로 잘못된 한 비트를 찾아 고치고, 시간이 지나며 쌓이는 오류까지 주기적으로 훑어 없애는 것과 같음

## Ⅶ. 결론

- 해밍 코드는 단일 비트 오류를 정정하며 이중 오류 검출은 SECDED, 버스트 오류 검출은 CRC를 선택해야 함
- 메모리 오류가 누적되는 시스템은 SECDED와 주기적 스크러빙을 결합하고, 미정정 오류율이 높으면 더 강한 ECC로 전환해야 함

### 쉽게 이해하기 (학습용)
- 한 비트짜리 실수는 스스로 고칠 수 있지만, 실수가 여러 개 겹치거나 자주 쌓이면 이 방식만으로는 부족해 더 강한 오류 정정 방식으로 바꿔야 함
