## 미리 알고가기

- 패리티 비트(parity bit): 정해진 비트 묶음 안에서 1의 개수가 짝수인지 홀수인지를 검사해 그 묶음에 오류가 있는지 판정하는 감시용 비트임. 물건을 상자에 담을 때마다 개수를 세어 두고 나중에 다시 세어 하나가 비었는지 확인하는 것과 같은 원리임
- 해밍 거리(Hamming distance): 길이가 같은 두 코드워드를 나란히 놓았을 때 값이 서로 다른 비트의 개수임. 해밍 거리가 클수록 두 코드워드가 오류로 인해 서로 뒤바뀔 위험이 낮음
- syndrome(신드롬): 수신 측이 같은 규칙으로 패리티를 다시 계산해 얻은 값들의 조합임. 이 값 자체가 별도의 탐색 없이 오류가 난 비트의 위치 번호를 바로 가리킴
- SECDED(Single Error Correction Double Error Detection): 단일 비트 오류는 정정하고 이중 비트 오류는 검출만 하도록 패리티를 하나 더 추가한 확장 방식임

## Ⅰ. 개요

- **정의/개념**: 해밍 코드(Hamming Code)는 전송할 데이터 비트 사이사이에 여러 개의 패리티 비트를 정해진 규칙으로 배치해 두었다가, 수신 측에서 같은 규칙으로 다시 계산한 패리티 값들의 조합(syndrome)만으로 오류가 난 비트의 위치를 바로 찾아 정정하는 오류 정정 부호(ECC, Error Correcting Code)임
- **배경/필요성**: 메모리 셀, 저장장치, 통신 채널은 잡음이나 방사선 입자 때문에 저장되거나 전송되는 비트 값이 우연히 뒤집히는 사고를 겪는데, 오류가 있었다는 사실만 알리는 검출 방식으로는 시스템을 멈추거나 재전송을 요청해야 하므로 오류 위치까지 스스로 짚어 즉시 복구하는 코드가 필요해졌음

## Ⅱ. 특징

- 해밍 코드는 여러 패리티 비트가 서로 다른 조합으로 데이터 비트를 겹쳐서 감시하도록 위치를 배치해 두므로, 수신 측에서 각 패리티를 다시 계산했을 때 어긋난 패리티들의 조합 자체가 오류 비트의 위치 번호(syndrome)가 됨
- 단일 비트 오류는 별도의 재전송 요청 없이 그 자리에서 값을 뒤집어 정정할 수 있어, 오류를 발견한 시점에 곧바로 복구가 끝남
- 패리티 비트를 하나 더 붙이면 이중 비트 오류까지 검출할 수 있는 SECDED로 확장할 수 있어, 정정 능력과 추가 비트 수 사이의 조정이 비교적 유연함
- 다만 오류 정정 능력이 단일 비트 수준에 맞춰져 있어, 인접한 여러 비트가 한꺼번에 틀리는 버스트 오류나 두 비트 이상이 겹치는 오류에서는 엉뚱한 비트를 정정하는 오정정이 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 패리티 | 해밍 코드 | CRC(Cyclic Redundancy Check) |
|:---|:---|:---|:---|
| 할 수 있는 일 | 오류가 있었다는 사실만 알림 | 오류 위치를 찾아 그 자리에서 정정함 | 오류 여부를 매우 높은 확률로 검출함 |
| 오류 정정 가능 여부 | 불가능함 | 단일 비트 오류는 가능함 | 불가능하며 재전송으로 대응함 |
| 계산 비용 | 낮음 | 중간이며 패리티 비트 수만큼 늘어남 | 중간이며 다항식 나눗셈 연산이 필요함 |
| 대표 활용 | 간단한 자체 점검 | ECC(Error Correcting Code) 메모리처럼 즉시 정정이 필요한 곳 | 네트워크 프레임처럼 정정보다 검출 정확도가 중요한 곳 |

> 요약: 단순 패리티는 오류 유무만 알리고, 해밍 코드는 단일 비트를 스스로 정정하며, CRC는 정정 대신 검출 정확도를 높이는 데 최적화되어 있음.

## Ⅳ. 구성요소 및 구조

```text
+-------------+      +-------------+      +-------------+
| 데이터 비트 | ---> | 패리티 비트 | ---> | 코드워드    |
| (정보 원본) |      | (겹침 배치) |      | (전송 단위) |
+-------------+      +-------------+      +-------------+
                                                  |
                                                  v
                                           +-------------+
                                           | syndrome    |
                                           | (오류 위치) |
                                           +-------------+
```

| 구성요소 | 설명 |
|:---|:---|
| 데이터 비트 | 실제 전송할 정보 비트로, 위치 번호가 2의 거듭제곱이 아닌 자리(3, 5, 6, 7 ...)에 배치되어 여러 패리티 비트의 검사 범위에 동시에 겹쳐 들어감 |
| 패리티 비트 | 위치 번호가 2의 거듭제곱인 자리(1, 2, 4, 8 ...)에 배치되며, 자신의 위치를 이진수로 나타냈을 때 그 자리가 1인 데이터 비트들만 묶어 짝수 패리티 값을 계산함 |
| 코드워드 | 데이터 비트 $k$개와 패리티 비트 $m$개를 합친 길이 $n=k+m$의 전송 단위이며, 모든 오류 위치를 표현하려면 $2^m \geq k+m+1$ 조건을 만족해야 함 |
| syndrome | 수신 측이 같은 겹침 규칙으로 각 패리티를 재계산해 어긋난 패리티 번호만 이진수로 합친 값이며, 0이면 오류 없음을 뜻하고 0이 아니면 그 값 자체가 오류 비트의 위치 번호가 됨 |

> 요약: 데이터 비트를 패리티 비트들이 서로 다른 조합으로 겹쳐 감시하도록 배치해 두어, 수신 측이 재계산한 syndrome 하나로 오류 위치가 바로 드러남.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+      +----------+      +----------+      +----------+      +----------+
| 위치식별 | ---> | 패리티   | ---> | 전송/    | ---> | syndrome | ---> | 정정/    |
|          |      | 계산     |      | 수신     |      | 계산     |      | 반환     |
+----------+      +----------+      +----------+      +----------+      +----------+
```

1. **위치 식별**: 데이터 비트 수 $k$에 맞춰 $2^m \geq k+m+1$을 만족하는 최소 패리티 개수 $m$을 정하고 각 비트를 코드워드 위치에 배치함
2. **패리티 계산**: 송신 측이 각 패리티 비트마다 자신이 겹쳐 감시하는 데이터 비트들의 1의 개수를 세어 짝수 패리티 값을 채워 코드워드를 완성함
3. **전송/수신**: 완성된 코드워드가 채널을 통해 전달되며, 전송 중 잡음이나 방사선 입자로 한 비트가 뒤집힐 수 있음
4. **syndrome 계산**: 수신 측이 같은 겹침 규칙으로 각 패리티를 다시 계산해 원래 값과 대조한 결과를 이진수로 모으면 그 값이 곧 오류 비트의 위치 번호가 됨
5. **정정/반환**: syndrome이 0이 아니면 해당 위치 비트를 반전해 즉시 정정하고, 0이면 오류 없이 데이터 비트만 추려 반환함

## Ⅵ. 실무 적용 및 유의점

1. ECC 메모리 모듈처럼 셀 하나가 방사선 입자에 맞아 값이 뒤집히는 단일 비트 오류가 주로 발생하는 환경에서는 해밍 코드 기반 SECDED를 적용하지만, 인접한 여러 셀이 한꺼번에 틀리는 버스트 오류에서는 겹침 패턴이 뒤섞여 오정정이 발생할 수 있으므로 오류를 여러 코드워드에 나눠 흩뿌리는 인터리빙(interleaving)을 함께 적용하고 단일 비트 정정 횟수와 이중 비트 검출 횟수로 상태를 확인함
2. 위성 통신처럼 왕복 지연이 커서 재전송 요청 자체가 큰 비용인 링크에서는 해밍 코드로 그 자리에서 정정해 재전송 횟수를 줄이지만 패리티 비트 수가 늘어날수록 대역폭을 잠식하므로 데이터 비트 수 $k$에 맞춘 최소 패리티 개수만 배치하고 유효 처리량과 재전송 요청 횟수로 오버헤드를 확인함

## Ⅶ. 결론

해밍 코드는 패리티 비트를 겹쳐 배치해 syndrome만으로 오류 위치를 즉시 정정하는 대가로 데이터 비트 수에 비례한 패리티 오버헤드를 치러야 하므로, 재전송 비용이 크고 단일 비트 오류가 지배적인 환경에서는 유리하지만 버스트 오류나 이중 비트 오류가 잦은 환경에서는 SECDED 확장이나 인터리빙 같은 보완 없이는 오정정 위험을 피할 수 없다는 점이 최종 선택 기준임.
