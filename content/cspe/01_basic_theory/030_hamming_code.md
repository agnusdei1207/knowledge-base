## 미리 알고가기

- 에러 정정 부호(ECC): 전송 중 발생한 오류를 검출할 뿐만 아니라, 스스로 원래의 데이터를 복구할 수 있는 코딩 방식임
- 패리티 비트($Parity$ $Bit$): 데이터 내 1의 개수를 짝수 또는 홀수로 맞추어 오류 유무를 판별하기 위해 추가하는 비트임
- 신드롬($Syndrome$): 수신 측에서 패리티 비트를 다시 계산하여 얻은 결과값으로, 오류의 발생 여부와 위치 정보를 담고 있음
- 해밍 거리($Hamming$ $Distance$): 같은 길이를 가진 두 비트열 사이에서 서로 다른 비트의 개수를 의미함

## Ⅰ. 개요

- **정의/개념**: 해밍 코드는 데이터 비트에 다수의 패리티 비트를 특정 규칙(2의 거듭제곱 위치)으로 삽입하여 전송하고, 수신 측에서 신드롬 분석을 통해 단일 비트 오류의 위치를 찾아내어 스스로 정정하는 선형 블록 부호임
- **배경/필요성**: 데이터 통신이나 메모리 저장 과정에서 발생하는 비트 반전 오류($Bit$ $Flip$)를 재전송 없이 즉각 복구하여 시스템의 가동률($Availability$)을 높이고 통신 효율성을 확보하기 위해 사용됨

## Ⅱ. 특징

- 여러 개의 패리티 비트가 데이터 비트들을 중첩하여 감시하는 구조를 취하므로, 단일 비트 오류 시 오류가 발생한 정확한 위치(인덱스)를 수치적으로 도출할 수 있음
- 패리티 비트의 수($p$)와 데이터 비트의 수($d$) 사이에는 $2^p \geq d + p + 1$이라는 부등식이 성립해야 하며, 이를 통해 효율적인 코드워드 길이를 설계함
- 단일 비트 오류 정정($SEC$) 기능 외에도 전체 패리티 비트를 하나 더 추가하면 이중 비트 오류를 검출($DED$)할 수 있는 $SECDED$ 방식으로 확장이 가능함

## Ⅲ. 종류 및 비교

| 판단 기준 | 패리티 비트 (Parity) | 해밍 코드 (Hamming) | CRC (Cyclic Redundancy) |
|:---|:---|:---|:---|
| **오류 검출** | 단일 비트 (홀수 개) | 단일/이중 비트 | 다중 비트 (강력함) |
| **오류 정정** | 불가능 | 단일 비트 가능 | 불가능 |
| **오버헤드** | 매우 낮음 (1비트) | 중간 (로그 스케일) | 보통 (다항식 연산) |
| **주요 용도** | 간단한 하드웨어 체크 | $ECC$ 메모리, 내부 버스 | 네트워크 패킷 ($Ethernet$) |

> 요약: 해밍 코드는 재전송이 어려운 메모리 내부 연산 등에서 즉각적인 복구가 필요할 때 최적의 성능을 발휘함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 비트 ($D$) | 전송하고자 하는 실제 정보이며, 위치 번호가 2의 거듭제곱이 아닌 자리에 배치함 |
| 패리티 비트 ($P$) | 오류 검출 및 정정을 위한 부가 정보이며, 위치 번호 1, 2, 4, 8, ... 자리에 배치함 |
| 코드워드 ($Codeword$) | 데이터와 패리티가 결합된 최종 전송 비트열로, $n, k$ 부호($n$:전체, $k$:데이터)로 표기함 |
| 신드롬 연산 | 수신된 각 패리티 비트와 데이터 비트를 다시 XOR하여 오류 위치 번호를 생성하는 과정임 |

```text
[ 7비트 해밍 코드 배치 예시 (4비트 데이터) ]
P1 P2 D1 P3 D2 D3 D4
 1  2  3  4  5  6  7  (위치 번호)
- P1: 1, 3, 5, 7 자리 체크
- P2: 2, 3, 6, 7 자리 체크
- P3: 4, 5, 6, 7 자리 체크
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 패리티 비트 삽입| --> | 데이터 전송/수신| --> | 신드롬 생성/분석| --> | 위치 정정/복구|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **인코딩 단계** — 전송 데이터의 비트 수에 맞는 패리티 비트 개수를 산출하고, 각 패리티가 담당할 데이터 비트 영역을 정해 짝수(또는 홀수) 패리티 값을 채움
2. **전송 단계** — 구성된 코드워드를 채널을 통해 전송하며, 이때 외부 노이즈에 의해 특정 비트의 값이 반전될 수 있음
3. **디코딩 단계** — 수신 측에서 모든 패리티 그룹에 대해 다시 검사를 수행하고, 어긋난 패리티들의 위치 번호를 조합하여 신드롬 값을 생성함
4. **오류 정정** — 신드롬 값이 0이면 오류 없음, 0이 아니면 해당 번호 위치의 비트를 반전($0 \leftrightarrow 1$)시켜 원래 데이터를 복구함

## Ⅵ. 실무 적용 및 유의점

1. $ECC$ 메모리 설계 시 단일 비트 오류는 해밍 코드로 정정하지만, 인접 비트가 동시에 깨지는 버스트 오류($Burst$ $Error$)에는 취약하므로 비트들을 물리적으로 흩어 놓는 '인터리빙($Interleaving$)' 기법을 병행하여 정정 확률을 높여야 함
2. 네트워크 통신과 같이 패킷 단위로 대량의 데이터가 오가는 환경에서는 해밍 코드의 높은 오버헤드보다는 $CRC$와 같은 강력한 검출 기법과 $ARQ$(재전송 요청) 메커니즘을 결합하는 것이 전송 효율 면에서 더 유리함

## Ⅶ. 결론

- 해밍 코드는 수치적 논리만으로 데이터의 자가 치유 능력을 부여하는 획기적인 오류 제어 기술이며, 설계자는 시스템의 오류 발생 패턴과 허용 오버헤드를 분석하여 최적의 부호 구조와 정정 메커니즘을 구축해야 함
