## Ⅰ. 개요
- 정의: 데이터에 패리티 비트를 추가하여 1비트 오류를 스스로 찾아내어 교정하는 코드임
- 배경/필요성: 전송/저장 중 발생하는 비트 반전 오류를 실시간으로 복구하기 위해 사용됨
- 출제 의도: 해밍 코드의 생성 원리, 패리티 비트 위치 계산, 오류 정정 과정 평가

## Ⅱ. 구성요소
- ASCII 구조도 (7,4 Hamming)
  Bit Pos: 1  2  3  4  5  6  7
  Type   : P1 P2 D1 P4 D2 D3 D4  (P: Parity, D: Data)
           ^  ^     ^ (2^n positions)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 데이터 비트 | 실제 전송하고자 하는 정보 | 본문 |
| 패리티 비트 | 오류 검출/정정을 위해 추가된 중복 비트 | 검수 도장 |
| 해밍 거리 | 두 코드 사이의 서로 다른 비트 수 | 차이 점수 |
| 신드롬 (Syndrome) | 오류 발생 위치를 나타내는 결과 값 | 고장 지점 신호 |
> 요약: 2^n 위치에 패리티 비트를 삽입하여 다중 체크 구조를 형성함

## Ⅲ. 절차
- ASCII 흐름도
  [Data] -> [Parity Insertion] -> [Transmit] -> [Syndrome Calc] -> [Correction]

1. 패리티 위치 결정: 1, 2, 4, 8... 등 2의 거듭제곱 자리에 패리티를 배치함
2. 패리티 값 계산: 각 패리티가 담당하는 데이터 비트들의 짝수/홀수 패리티를 설정함
3. 수신 및 검사: 수신된 코드의 모든 패리티 체크를 다시 수행함
4. 오류 정정: 체크 결과(신드롬)가 0이 아니면 해당 위치의 비트를 반전시킴
> 요약: 신드롬 값이 곧 오류가 발생한 비트의 위치 번호가 됨

## Ⅳ. 문제점
- 오버헤드: 중복 비트 추가로 인해 실제 전송 효율이 감소함
- 다중 오류 한계: 기본 해밍 코드는 1비트 정정만 가능하며 2비트 이상은 불가함

## Ⅴ. 개선방안
- SEC-DED: 전체 패리티 비트를 하나 더 추가하여 1비트 정정 + 2비트 검출을 수행함
- 리드 솔로몬 코드: 버스트 오류(연속 오류)에 강한 상위 알고리즘을 적용함

## Ⅵ. 전망
- ECC 메모리: 서버용 RAM에서 데이터 신뢰성 확보를 위한 핵심 기술임
- 위성 통신: 재전송이 어려운 환경에서 강력한 전향 오류 수정(FEC) 기법으로 활용됨
