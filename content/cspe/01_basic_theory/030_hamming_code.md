## 미리 알고가기

- 패리티 비트: 데이터 비트들의 합 홀짝성을 검사하는 비트임
- Hamming distance: 두 코드워드가 서로 다른 비트 개수임
- SECDED: 단일 비트 정정, 이중 비트 검출을 확장한 방식임

## Ⅰ. 개요

- **정의/개념**: 해밍 코드는 데이터 비트에 다수의 패리티 비트를 배치해 단일 비트 오류의 위치를 찾아 정정하고, 일부 다중 비트 오류를 검출하는 선형 블록 코드임
- **배경/필요성**: 메모리, 저장장치, 통신 채널은 잡음과 방사선으로 비트 오류가 발생하므로 단순 검출을 넘어 즉시 정정 가능한 코드가 필요함

## Ⅱ. 특징

- 패리티 비트 조합으로 오류 위치를 syndrome 형태로 계산함
- 단일 비트 오류는 자동 정정 가능해 복구 속도가 빠름
- 추가 패리티를 붙이면 이중 비트 오류까지 검출 가능함
- 오류 정정 능력은 높지 않아 버스트 오류나 다중 비트 오류에는 한계가 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 패리티 | 해밍 코드 | CRC |
|:---|:---|:---|:---|
| 기능 | 오류 검출 | 단일 오류 정정 | 강한 검출 |
| 정정 가능 여부 | 불가 | 가능 | 불가 |
| 계산 복잡도 | 낮음 | 중간 | 중간 |
| 대표 적용 | 기초 검증 | ECC 메모리 | 네트워크 프레임 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 비트 | 실제 전달 정보이며 보호 대상임 |
| 패리티 비트 | 특정 위치 집합의 홀짝성을 검사하고 syndrome 계산의 기준임 |
| 코드워드 | 데이터와 패리티를 결합한 전송 단위이며 오류 내성이 생김 |
| syndrome 로직 | 오류 위치를 계산하고 정정 여부를 결정함 |

```text
+-----------+     +-----------+     +-----------+     +---------------+
| 데이터 비트   | --> | 패리티 비트  | --> | 코드워드     | --> | syndrome 로직 |
+-----------+     +-----------+     +-----------+     +---------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 비트배치 | --> | 패리티생성 | --> | 수신검사 | --> | 오류정정 |
+----------+     +----------+     +----------+     +----------+
```

1. **비트배치**: 데이터 비트와 패리티 비트 위치를 정함
2. **패리티생성**: 각 검사 집합의 패리티를 계산해 저장함
3. **수신검사**: 같은 규칙으로 syndrome을 다시 계산함
4. **오류정정**: syndrome 값이 가리키는 비트를 뒤집어 복구함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 다중 비트 오류에 취약해 두 비트 이상 오류는 오정정 위험이 있음
   - 해결방안: SECDED나 BCH, Reed-Solomon으로 보강하고 다중 오류 검출률로 검증함
2. 문제: 패리티 오버헤드가 생겨 데이터 대비 추가 비트가 필요함
   - 해결방안: 오류 발생률과 저장 비용을 기준으로 코드 길이를 설계하고 ECC 효율로 검증함
3. 문제: 실시간 경로 지연이 증가할 수 있어 syndrome 계산이 읽기 지연을 늘림
   - 해결방안: 하드웨어 병렬 계산과 파이프라인을 적용하고 메모리 read latency로 검증함

## Ⅶ. 적용 사례

- ECC 메모리에서는 DRAM의 단일 비트 오류를 자동 복구함, 확인 지표는 corrected error 수임
- 우주/항공 전자장치에서는 방사선 유발 비트 오류를 완화함, 확인 지표는 soft error rate임
- 산업용 통신 모듈에서는 저비용 채널 보호에 적용함, 확인 지표는 BER 감소율임

## Ⅷ. 결론

해밍 코드의 핵심은 낮은 오버헤드로 단일 비트 오류를 즉시 복구하는 데 있으므로, 오류 패턴이 단순한 구간에는 해밍 코드를, 다중 오류 환경에는 더 강한 ECC를 선택해야 함.
