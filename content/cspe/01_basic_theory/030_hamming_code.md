## 미리 알고가기

- 오류 검출: 수신 데이터에 오류가 있는지 판단하는 기능임
- 오류 정정: 오류가 난 위치를 찾아 원래 비트로 복구하는 기능임
- 패리티 비트: 특정 비트 집합의 1 개수가 짝수 또는 홀수가 되도록 추가하는 검사 비트임
- 해밍 거리: 두 코드워드가 서로 다른 비트 위치의 개수임
- 신드롬: 수신 코드워드의 패리티 검사 결과를 모아 오류 위치를 나타내는 값임

## Ⅰ. 개요

- **정의**: 해밍 코드는 데이터 비트에 패리티 비트를 배치하고 신드롬으로 오류 위치를 찾아 1비트 오류를 정정하는 선형 블록 코드임
- **배경/필요성**: 저장장치와 전송 채널에서는 잡음, 전기적 간섭, 방사선으로 비트 반전이 발생하므로 재전송 없이 즉시 오류를 정정할 수 있는 낮은 비용의 코드가 필요함.
- **비유**: 문서 곳곳에 검산 숫자를 넣어 틀린 칸의 위치를 역산하는 표 검사 방식과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해밍 코드 구성 원리 설명 | 패리티 위치, 검사 집합, 신드롬 | 단순 패리티와 혼동 |
| 오류 검출·정정 능력 구분 | SEC, SECDED, 해밍 거리 | 2비트 정정 가능으로 오해 |

> 요약: 해밍 코드는 패리티 검사 결과를 이진 위치 정보로 해석해 1비트 오류를 찾아 고치는 오류 제어 코드임.

## Ⅱ. 특징/비교

| 판단 기준 | 단순 패리티 | 해밍 코드 |
|:---|:---|:---|
| 오류 검출 | 홀수 개 오류 존재 여부만 알 수 있음 | 신드롬으로 1비트 오류 위치를 알 수 있음 |
| 오류 정정 | 오류 위치를 모르므로 정정할 수 없음 | 1비트 오류는 비트 반전으로 정정 가능함 |
| 중복 비트 | 패리티 1비트만 추가하는 경우가 많음 | `2^r >= m + r + 1` 기준으로 여러 패리티를 배치함 |
| 선택 기준 | 낮은 비용의 단순 검출에 적합함 | 메모리 ECC처럼 즉시 정정이 필요한 영역에 적합함 |

- **거리 기준**: 최소 해밍 거리 3이면 1비트 정정, 거리 4인 확장 해밍 코드는 1비트 정정과 2비트 검출이 가능함.
- **배치 기준**: 패리티 비트는 1, 2, 4, 8번처럼 2의 거듭제곱 위치에 놓아 검사 집합을 구성함.
- **운영 기준**: 다중 비트 오류가 자주 발생하는 환경에는 더 강한 ECC나 인터리빙이 필요함.

> 요약: 해밍 코드는 단순 패리티보다 중복 비트를 더 쓰는 대신 오류 위치를 계산해 1비트 정정을 수행함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Data Bits  | ---> | Parity     | ---> | Codeword   |
| m bits     |      | Positions  |      | m + r bits |
+------------+      +------------+      +------------+
       |                   |                   |
       v                   v                   v
+------------+      +------------+      +------------+
| Check Set  |      | Syndrome   |      | Corrected  |
| Coverage   |      | Value      |      | Data       |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 데이터 비트 | 실제 저장하거나 전송하려는 원본 정보 비트임 | 편지 내용 |
| 패리티 비트 | 특정 위치에 삽입되어 여러 비트 집합의 짝수/홀수 조건을 맞춤 | 검산 숫자 |
| 코드워드 | 데이터 비트와 패리티 비트를 합친 전송·저장 단위임 | 검산 포함 문서 |
| 검사 집합 | 각 패리티가 담당하는 비트 위치 묶음이며 이진 인덱스 기준으로 정함 | 점검 구역 |
| 신드롬 | 패리티 재계산 결과를 모아 오류 위치를 나타내는 이진값임 | 오류 좌표 |

> 요약: 해밍 코드는 데이터와 패리티를 코드워드로 만들고, 수신 시 검사 집합별 패리티 결과를 신드롬으로 해석해 오류 위치를 찾음.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Place      | ---> | Compute    | ---> | Recheck    | ---> | Correct    |
| Parity     |      | Codeword   |      | Syndrome   |      | Bit/Data   |
+------------+      +------------+      +------------+      +------------+
```

1. **패리티 위치 결정**: 데이터 비트 수 `m`에 대해 `2^r >= m + r + 1`을 만족하는 패리티 수 `r`을 정함.
2. **코드워드 생성**: 1, 2, 4, 8번 위치에 패리티를 배치하고 각 검사 집합의 패리티 값을 계산함.
3. **신드롬 계산**: 수신 측에서 같은 검사 집합의 패리티를 다시 계산해 오류 위치 값을 구성함.
4. **오류 정정**: 신드롬이 0이면 정상, 0이 아니면 해당 위치 비트를 반전하고 데이터 비트를 추출함.

> 요약: 해밍 코드는 패리티 배치, 코드워드 생성, 신드롬 계산, 오류 비트 반전 순서로 1비트 오류를 정정함.

## Ⅴ. 문제점

- **P1 다중 비트 취약성**: 기본 해밍 코드는 2비트 오류를 잘못된 1비트 오류로 해석해 오정정할 수 있음.
- **P2 중복 비트 오버헤드**: 데이터가 작거나 오류율이 낮은 환경에서는 패리티 비트가 상대적으로 큰 저장·전송 비용이 됨.
- **P3 버스트 오류 대응 한계**: 연속된 여러 비트가 손상되는 채널에서는 단일 비트 정정 구조만으로 충분하지 않음.

> 요약: 해밍 코드는 낮은 비용의 1비트 정정에는 적합하지만 다중·버스트 오류와 오버헤드 관리가 한계임.

## Ⅵ. 개선방안

- **P1 대응**: 전체 패리티를 추가한 SECDED 확장 해밍 코드로 1비트 정정과 2비트 검출을 구분함. (확인: double error detect 테스트)
- **P2 대응**: 오류율, 데이터 폭, 지연 요구를 기준으로 패리티, 해밍, BCH, LDPC 중 적절한 코드를 선택함. (확인: redundancy ratio)
- **P3 대응**: 인터리빙, Reed-Solomon, CRC+재전송을 결합해 연속 오류를 분산 또는 검출함. (확인: burst error 길이)

> 요약: 해밍 코드는 SECDED와 더 강한 코드 조합을 통해 다중·버스트 오류 환경에 맞게 확장해야 함.

## Ⅶ. 전망

- **발전 방향**: 서버 메모리 ECC, 저장장치, 우주·자동차 전장 시스템에서 저지연 오류 정정 코드의 필요성은 계속 증가할 전망임.
- **기술사적 판단**: 오류율과 지연 예산이 낮은 메모리 내부에는 해밍 계열이 적합하지만, 고잡음 채널에는 더 강한 코드가 필요함.
- **기술사 제언**: 답안에서는 패리티 위치, 신드롬, SEC/DED 한계를 수식보다 절차 중심으로 설명해야 함.
