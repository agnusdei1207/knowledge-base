# 해밍 코드·오류 검출·정정 (Hamming Code Error Detection)

## 1. 개요

- **정의/개념**: 해밍 코드는 데이터 비트에 패리티 비트를 삽입해 수신 데이터의 오류 위치를 신드롬으로 찾아 1비트 오류를 정정하는 선형 오류 정정 코드이다.
- **배경/필요성**: 저장장치, 메모리, 통신 채널에서는 잡음으로 비트 오류가 발생하므로 재전송 없이 오류를 검출·정정하는 구조가 필요하다.

해밍 코드는 오류가 "났는지"뿐 아니라 "어느 위치인지"를 찾는다는 점에서 단순 패리티보다 실무적 의미가 크다.

## 2. 특징 및 비교

| 구분 | 단순 패리티 | 해밍 코드 | CRC |
|---|---|---|---|
| 목적 | 오류 검출 | 1비트 오류 정정 | burst 오류 검출 |
| 위치 식별 | 어려움 | 신드롬으로 가능 | 검출 중심 |
| 오버헤드 | 낮음 | 중간 | 다항식 길이에 따라 다름 |
| 활용 | 간단 검증 | ECC 메모리 | 네트워크 프레임 |

선택 기준은 오류 유형, 정정 필요성, 패리티 오버헤드, 지연 허용 범위이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Data Bit | 실제 전송·저장할 정보 | 보호 대상 |
| Parity Bit | 특정 위치 집합의 짝수·홀수 검증 | `2^k` 위치 배치 |
| Syndrome | 수신 후 패리티 검사 결과 | 오류 위치 계산 |
| Hamming Distance | 코드워드 간 최소 거리 | 검출·정정 능력 |
| SEC/DED | Single Error Correction, Double Error Detection | 확장 해밍 코드 |

```text
+----------+      +------------+      +----------+      +----------+
| 데이터비트 | ---> | 패리티삽입 | ---> | 전송/저장 | ---> | 신드롬검사 |
+----------+      +------------+      +----------+      +----------+
                                                       |
                                                       v
                                                 오류위치 정정
```

패리티 위치와 신드롬 계산이 연결되어야 해밍 코드의 정정 원리가 직관적으로 설명된다.

## 4. 문제점 및 개선방안

1. **다중 비트 오류 한계**
   - 기본 해밍 코드는 1비트 오류 정정 중심이며 다중 오류에서는 오판 가능성이 있다.
   - **개선방안**: SEC/DED, CRC, Reed-Solomon 등 오류 특성에 맞는 코드를 선택한다.

2. **패리티 오버헤드**
   - 패리티 비트가 늘면 저장 공간과 처리 지연이 증가한다.
   - **개선방안**: 목표 오류율과 데이터 크기에 맞춰 코드율을 산정한다.

3. **오류 모델 부적합**
   - 연속 burst 오류가 많은 채널에서는 해밍 코드만으로 부족하다.
   - **개선방안**: interleaving, CRC, burst 오류 정정 코드를 결합한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| ECC 메모리 | 메모리 워드에 SEC/DED 코드 적용 | corrected error count |
| 저장장치 | 플래시·디스크 데이터 보호에 ECC 적용 | UBER, 복구율 |
| 통신 장치 | 오류 검출·정정 코드로 링크 신뢰성 보강 | BER, 재전송률 |

## 6. 결론

해밍 코드는 패리티와 신드롬을 이용해 1비트 오류 위치를 찾고 정정하는 대표적인 오류 제어 기법이다. 패리티 배치, 신드롬 계산, SEC/DED 한계가 하나의 흐름으로 연결되어야 오류 검출과 정정의 차이가 분명해진다.
