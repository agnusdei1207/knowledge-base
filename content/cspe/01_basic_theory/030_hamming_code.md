## 미리 알고가기

- 오류 검출: 수신 데이터에 비트 오류가 있는지 찾아내는 기능임
- 오류 정정: 오류 위치를 찾아 원래 값으로 복구하는 기능임
- 패리티 비트: 데이터 비트 일부를 검사하기 위해 추가하는 검사용 비트임
- 해밍 거리: 같은 길이의 두 비트열에서 서로 다른 위치의 개수임
- 신드롬: 수신 후 패리티 검사를 다시 수행해 얻는 오류 위치 정보임
- SECDED: 단일 비트 오류는 정정하고 이중 비트 오류는 검출하는 방식임

## 작성 근거(검토용)

- 기출 키워드이므로 정의에서 패리티 위치, 신드롬, 단일 비트 정정을 한 문장에 포함함
- 특징은 위치 산출 원리·패리티 수 조건·SECDED 확장·버스트 오류 한계를 중심으로 선별함
- Ⅲ은 패리티·해밍·SECDED·CRC를 비교해 검출과 정정의 차이를 명확히 보이게 함
- Ⅳ와 Ⅴ는 7비트 예시와 절차를 결합해 계산 문제와 서술형 답안을 모두 대비하게 함
- ECC 메모리와 네트워크 패킷처럼 정정 우선 환경과 검출 우선 환경을 구분함

## Ⅰ. 개요

- **정의/개념**: 해밍 코드는 코드워드의 2의 거듭제곱 위치에 패리티 비트를 삽입하고 신드롬으로 단일 비트 오류 위치를 찾아 정정하는 선형 블록 부호임
- **배경/필요성**: 메모리·내부 버스 오류를 즉시 복구하기 위해 적은 중복 비트로 검출·정정하는 방법이 필요함

## Ⅱ. 특징

- 여러 패리티 비트가 데이터 비트를 겹쳐 검사해 오류 위치를 이진수로 산출함
- 데이터 비트 $d$와 패리티 비트 $p$는 $2^p \geq d + p + 1$ 조건을 만족해야 함
- 기본 해밍 코드는 단일 비트 오류를 정정하고, 전체 패리티를 추가하면 SECDED가 됨
- 버스트 오류나 다중 비트 오류에는 약하므로 오류 패턴에 맞는 보완 기법이 필요함

## Ⅲ. 종류 및 비교

| 방식 | 오류 검출 | 오류 정정 | 오버헤드 | 적합 환경 |
|:---|:---|:---|:---|:---|
| 단순 패리티 | 홀수 개 오류 | 불가 | 1비트 | 간단한 링크 확인 |
| 해밍 코드 | 단일 비트 오류 | 단일 비트 | $p$개 패리티 비트 | ECC 메모리·내부 버스 |
| SECDED | 이중 오류 검출 | 단일 비트 | 해밍 코드+1비트 | 서버 메모리 |
| CRC | 다중·버스트 오류 | 불가 | 다항식 길이 | 네트워크 프레임 |

> 요약: 해밍 코드는 재전송 없이 단일 비트 복구가 필요할 때 적합하고, CRC는 다중·버스트 오류 검출에 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 비트($D$) | 보호 대상 정보이며 2의 거듭제곱이 아닌 위치에 배치함 |
| 패리티 비트($P$) | 위치 1, 2, 4, 8처럼 2의 거듭제곱 자리에 배치함 |
| 코드워드 | 데이터와 패리티를 결합한 전송·저장 단위임 |
| 패리티 그룹 | 각 패리티 비트가 검사할 위치 집합이며 겹침 구조로 오류 위치를 구분함 |
| 신드롬 | 실패한 패리티 번호를 합쳐 오류 비트 위치를 가리키는 값임 |

```text
위치: 1  2  3  4  5  6  7
비트: P1 P2 D1 P4 D2 D3 D4

P1 검사: 1·3·5·7
P2 검사: 2·3·6·7
P4 검사: 4·5·6·7
```

> 요약: 패리티 그룹이 겹쳐 검사되므로 실패한 검사 번호의 합이 오류 위치가 됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 패리티 추가 | --> | 저장·전송  | --> | 신드롬 계산 | --> | 오류 정정  |
+----------+     +----------+     +----------+     +----------+
```

1. **패리티 배치**: 데이터 길이에 맞는 패리티 수를 정하고 2의 거듭제곱 위치에 둠
2. **코드워드 생성**: 각 패리티 그룹에서 1의 개수가 짝수 또는 홀수가 되도록 값을 채움
3. **신드롬 계산**: 수신 후 같은 그룹을 다시 검사해 실패한 패리티 위치를 모음
4. **오류 정정**: 신드롬이 0이면 정상이고, 0이 아니면 해당 위치 비트를 반전함

> 요약: 해밍 코드는 신드롬이 가리키는 단일 비트를 반전해 재전송 없이 오류를 복구함.

## Ⅵ. 실무 사례

1. ECC 메모리는 단일 비트 오류를 해밍 코드로 정정하되, 버스트 오류에는 취약하므로 인터리빙과 메모리 스크러빙을 병행하고 정정 카운터로 상태를 확인함
2. 네트워크 패킷은 오류가 묶음으로 발생하기 쉬우므로 CRC와 재전송을 우선 적용하고 프레임 오류율과 재전송률로 적합성을 검증함

## Ⅶ. 결론

- 해밍 코드는 작은 중복 비트로 단일 비트 오류를 즉시 복구하는 방식이므로 오류 패턴이 단일 무작위 오류인지 확인하고 SECDED나 CRC와 조합해야 함
