## 미리 알고가기

- **해밍 거리(Hamming Distance)**: 같은 길이의 두 비트열 사이에서 서로 다른 비트의 개수. 코드 간 최소 해밍 거리가 오류 검출 및 정정 능력을 결정함
- **패리티 비트(Parity Bit)**: 데이터 내 1의 개수를 짝수 또는 홀수로 맞추기 위해 추가하는 비트. 단순 패리티는 검출만 가능함
- **신드롬(Syndrome)**: 수신 측에서 수신된 코드로부터 계산한 결과값. 이 값이 0이면 오류 없음, 0이 아니면 오류의 위치를 지목함

## Ⅰ. 개요

- **정의/개념**: 해밍 코드(Hamming Code)는 데이터 비트에 여러 개의 패리티 비트를 특정 규칙에 따라 추가하여, 수신 측에서 오류가 발생한 비트의 위치를 정확히 찾아내어 스스로 정정(Forward Error Correction)할 수 있게 만든 코드임. 기본적으로 1비트의 오류 정정(SEC, Single Error Correction) 기능을 가짐
- **배경/필요성**: 단순 패리티 검사 방식은 오류의 존재 여부만 알 수 있고 위치를 모르는 한계가 있음. 특히 반도체 메모리(DRAM)의 소프트 에러(Soft Error)나 위성 통신처럼 데이터 재전송이 불가능하거나 비용이 매우 큰 환경에서는 읽는 즉시, 혹은 받는 즉시 스스로 복구하는 능력이 필수적임. 해밍 코드는 패리티 비트들이 서로 다른 영역을 중첩하여 감시하게 함으로써, '스무고개'식 이진 탐색 원리를 통해 오류 비트의 주소를 도출해 냄

## Ⅱ. 특징 및 비교

### 가. 오류 검출 및 정정 기법 비교

| 구분 | 단순 패리티 (Parity) | 해밍 코드 (Hamming) | CRC (Cyclic Redundancy Check) |
|:---|:---|:---|:---|
| 주요 기능 | 1비트 오류 검출 | 1비트 오류 정정 | 대량의 버스트(Burst) 오류 검출 |
| 오류 정정 | 불가 | 가능 (1비트 정정) | 불가 |
| 구현 방식 | XOR 연산 (가벼움) | 비트 위치별 패리티 중첩 | 다항식 나눗셈 (Modulo-2) |
| 오버헤드 | 데이터당 1비트 고정 | 데이터 길이에 log 비례 증가 | 생성 다항식 차수만큼 추가 |
| 적용 분야 | 직렬 통신 초기 모델 | ECC 메모리, L1/L2 캐시 | 이더넷 프레임, 하드디스크 블록 |

> 요약: 단순 검출은 패리티, 즉시 정정은 해밍, 뭉텅이 오류 검출은 CRC가 담당함

### 나. 해밍 거리와 코드 능력의 상관관계
- **검출 능력**: 최소 해밍 거리가 $d$일 때, $d-1$ 비트까지의 오류를 검출 가능
- **정정 능력**: 최소 해밍 거리가 $d$일 때, $(d-1)/2$ 비트까지의 오류를 정정 가능
- **기본 해밍 코드**: 해밍 거리 $d=3$으로, 2비트 검출 및 1비트 정정 수행

## Ⅲ. 구성요소/구조

### 가. 패리티 비트 배치 및 감시 원리 (7, 4 해밍 코드 예시)

데이터 4비트(D)와 패리티 3비트(P)를 혼합하여 총 7비트를 구성하며, 패리티는 2의 거듭제곱($2^n$) 자리에 배치함.

```text
비트 위치:   1    2    3    4    5    6    7
구성 요소:  [P1] [P2] [D1] [P3] [D2] [D3] [D4]

감시 범위 (위치 번호의 이진수 비트 포함 여부):
- P1 (001): 1, 3, 5, 7번 비트 감시
- P2 (010): 2, 3, 6, 7번 비트 감시
- P3 (100): 4, 5, 6, 7번 비트 감시
```

### 나. 오류 정정 프로세스 (Syndrome 도출)

| 단계 | 수행 내용 | 핵심 원리 |
|:---|:---|:---|
| 인코딩 | 2^n 위치에 패리티 삽입 및 XOR 연산 | 데이터별 감시 구역 할당 |
| 전송/저장 | 노이즈나 입자에 의해 비트 반전 발생 가능 | 물리적 오류 발생 |
| 신드롬 계산 | 수신된 패리티 검사 결과를 이진수로 나열 | 깨진 패리티들의 조합 확인 |
| 위치 식별 | 신드롬 값(S)이 0이 아니면 S번째 비트 정정 | 이진 주소값 = 오류 위치 |

> 요약: 중첩된 패리티 비트들이 각자의 검사 결과(0/1)를 모아 오류 비트의 이진 주소를 형성함

## Ⅳ. 문제점 및 개선방안

1. **2비트 이상 오류 발생 시 오정정(Mis-correction)**: 해밍 거리 3인 기본 코드는 2비트가 동시에 뒤집히면 엉뚱한 세 번째 비트를 오류로 지목하여 데이터를 더 파괴함
   - **개선방안**: 전체 비트에 대한 패리티를 하나 더 추가하여 해밍 거리 4를 만드는 SEC-DED(Single Error Correction, Double Error Detection) 기법을 사용하여 2비트 오류는 검출만 하고 정지함

2. **버스트 오류(Burst Error) 취약성**: 연속된 비트가 뭉텅이로 깨지는 환경에서는 해밍 코드의 1비트 정정 능력이 무의미해짐
   - **개선방안**: 여러 코드워드의 비트를 흩뿌려 전송하는 '인터리빙(Interleaving)' 기법을 병용하여 버스트 오류를 여러 개의 1비트 오류로 분산시켜 정정함

3. **데이터 길이 증가에 따른 연산 부하**: 데이터가 매우 길어지면 필요한 패리티 비트 수와 연산량이 증가함
   - **개선방안**: 64비트 워드당 8비트 패리티를 쓰는 식의 적절한 블록 단위 설계를 적용하여 지연 시간(Latency)과 정정 능력 사이의 트레이드오프를 조절함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 서버용 ECC DRAM | 64비트 데이터마다 8비트 SEC-DED 체크비트 할당 | 시스템 업타임, 정정 발생 로그 |
| SSD 컨트롤러 (BCH) | NAND 플래시의 비트 열화 복구를 위해 확장된 해밍 기반 코드 사용 | UBER(Uncorrectable Bit Error Rate) |
| 위성/우주 통신 | 재전송이 불가능한 장거리 링크에서 FEC의 기본 모듈로 활용 | BER(Bit Error Rate), 정정 성공률 |

> 요약: 다시 받을 수 없는 고신뢰 데이터 환경에서 해밍 코드는 최후의 보루 역할을 수행함

## Ⅵ. 결론

해밍 코드는 정보이론의 관점에서 데이터에 의도적인 중복성을 부여하여 신뢰성을 확보하는 고전적이면서도 가장 효율적인 오류 정정 기술임. 2의 거듭제곱 자리 배치라는 간단한 규칙으로 오류 위치를 수치화한 설계는 현대 컴퓨터 아키텍처의 메모리 신뢰성 확보에 지대한 공헌을 함.

향후 양자 컴퓨팅의 오류 정정이나 초고속 통신 환경에서도 해밍 코드의 근본 원리인 '선형 블록 코드'와 '중첩 감시'는 여전히 핵심 기술로 쓰일 것임. 기술사는 채널의 오류 특성(Random vs Burst)에 맞춰 해밍 코드 단독 사용, SEC-DED 확장, 혹은 리드-솔로몬 코드와의 결합 등을 유연하게 결정할 수 있어야 함.
