# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 순서 논리 회로(Sequential Logic)는 **현재 입력**과 **과거 상태(기억)**를 함께 고려해 출력을 결정하는 **기억력을 가진** 논리 회로이며, 플립플롭(Flip-Flop)·레지스터·카운터가 대표적이다.
- **왜 필요한가**: 조합 회로(028)는 전기가 끊기거나 입력이 바뀌면 결과가 즉시 사라진다. 변수 값을 저장하고(레지스터), 프로그램 실행 순서를 추적하려면(프로그램 카운터), 상태를 다음 클럭까지 유지하는 기억 장치가 필수이다.
- **핵심 직관**: 출력이 다시 입력으로 되돌아오는 **피드백 루프** 구조이다. "내가 직전에 무슨 상태였는지"를 기억하는 도어락 비밀번호 입력과 같다 — 앞자리를 기억해야 전체 조합을 판단할 수 있다.

## 핵심 용어 정리 (내부에 등장하는 것들)

순서 논리의 핵심 기억 소자와 타이밍 개념을 세운다. 기억 없이 연산만 하는 조합 회로는 028 참조.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 순서 논리 회로 (상위 키워드) | 피드백 루프로 과거 상태를 기억하며 출력을 결정하는 회로 | 기억력 있는 계산기 |
| 클럭 신호 (Clock) | 회로 전체의 박자를 맞추는 주기적 펄스 신호 | 오케스트라 지휘봉(틱-톡) |
| 래치 (Latch) | 레벨 트리거(Level-triggered) — 클럭이 High인 구간 내내 입력에 반응하는 비동기 기억 소자 | 문이 열려 있는 동안 자유 출입 |
| 플립플롭 (Flip-Flop) | 엣지 트리거(Edge-triggered) — 클럭이 변하는 찰나에만 입력을 캡처하는 동기 기억 소자 | 클럭 변환점에서만 문이 열림 |
| SR 플립플롭 | Set(1)/Reset(0) 핀으로 제어, S=R=1 금지 상태 존재 | 가장 원시적인 피드백 메모리 |
| D 플립플롭 | 입력 D를 클럭 엣지에 그대로 캡처 — 현대 표준 기억 소자 | 1칸짜리 안전 메모리 상자 |
| JK 플립플롭 | SR의 금지 상태를 해결 — J=K=1이면 Toggle(반전) | 카운터·분주기 핵심 소자 |
| 레지스터 (Register) | D 플립플롭 N개를 병렬로 묶어 N비트를 동시 저장 | CPU 내부의 초고속 임시 메모리 |
| 카운터 (Counter) | 클럭마다 숫자를 증가/감소시키는 회로 | 프로그램 카운터(PC) |
| 셋업 타임 (Setup Time) | 클럭 엣지 전에 데이터가 안정적으로 유지되어야 하는 최소 시간 | 문 닫히기 전에 들어와야 하는 마감 시간 |
| 홀드 타임 (Hold Time) | 클럭 엣지 후에 데이터가 유지되어야 하는 최소 시간 | 문 닫힌 직후 움직이면 안 되는 대기 시간 |
| 메타스테빌리티 | 셋업/홀드 타임 위반 시 0도 1도 아닌 중간 전압에 빠지는 불확정 상태 | 동전이 세워진 채로 멈추는 현상 |

## 깊이 이해
- **배경·문제의식**: 조합 회로의 연산 결과를 다음 연산에 쓰려면 임시 보관이 필요하다. 출력을 다시 입력으로 넣는 피드백 루프를 만들었지만, 제어 없이 빙글빙글 도는 것을 방지하기 위해 '클럭(박자)'이라는 통제 신호를 도입했다.
- **작동 원리**:
  - **SR 래치**: NOR 게이트 2개를 교차 피드백으로 연결한 가장 단순한 형태. S=1이면 Q=1(Set), R=1이면 Q=0(Reset), S=R=1은 금지 상태(불확정).
  - **D 플립플롭**: SR의 금지 상태를 해결하기 위해 입력을 D 하나로 합치고, 클럭 엣지에서만 D의 값을 캡처(Q←D)한다. 가장 안정적이며 현대 아키텍처의 표준 기억 소자이다.
  - **셋업/홀드 타임**: 클럭 엣지 전 최소 t_setup 동안 D가 안정, 엣지 후 최소 t_hold 동안 유지되어야 한다. 위반 시 메타스테빌리티(중간 전압)에 빠져 전체 파이프라인이 오동작한다.
  - **레벨 vs 엣지 트리거**: 래치는 클럭 High 구간 내내 입력 변화에 반응해 글리치가 전파될 수 있지만, 플립플롭은 엣지 찰나에만 캡처해 노이즈를 차단한다.
- **비유**: 회전문(플립플롭)은 평소 잠겨서 사람이 갇혀(기억) 있다가, 경비원이 버튼을 누를 때(클럭 엣지)만 한 바퀴 돌면서 새 사람이 들어가고 이전 사람이 나온다.
- **구체 예시**: D 플립플롭 32개를 나란히 놓고 클럭선을 하나로 묶으면 32비트 레지스터가 된다. CPU의 범용 레지스터(R0~R31), 프로그램 카운터(PC), 상태 레지스터(PSR) 모두 이 원리로 구성된다.
- **흔한 오해·주의점**:
  - **"래치와 플립플롭은 같다"**: 래치는 레벨 트리거(High 구간 반응), 플립플롭은 엣지 트리거(변환 순간 반응)로, 동기화 안정성이 근본적으로 다르다.
  - **"SRAM과 래치는 무관하다"**: SRAM 셀은 인버터 2개를 피드백으로 엮은 래치 구조(6T)이며, 이것이 캐시 메모리(L1/L2)의 물리적 기반이다.

## 연결 개념
- **조합 논리 회로 (028)**: 순서 회로의 연산부(Next-state Logic·Output Logic)를 구성하는 기억 없는 블록.
- **FSM — 유한 상태 기계**: 순서 회로로 구현되는 상태 천이 모델(무어/밀리 기계).
- **CPU 아키텍처·파이프라인 (031 등)**: 파이프라인 스테이지 사이의 레지스터(파이프라인 레지스터)가 순서 회로의 실무 적용.
- **SRAM/캐시 메모리**: 래치 원리로 구성된 초고속 메모리.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 순서 논리 회로는 조합 회로에 기억 소자(플립플롭)와 피드백 루프를 결합해 현재 입력과 과거 상태가 함께 출력을 결정하는 동기식 상태 머신임.
> 2. **가치**: 클럭 엣지에 맞춰 상태를 갱신해 연산 결과를 안전하게 보존하며, CPU 레지스터·프로그램 카운터·SRAM 캐시의 물리적 기반이 됨.
> 3. **판단 포인트**: 셋업/홀드 타임 위반 시 메타스테빌리티 발생으로 파이프라인 오동작이 가능하므로, 클럭 도메인 교차(CDC) 시 더블 플립플롭 동기화기가 필수임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기억 소자의 원리와 동기화 | 피드백 루프, 클럭 동기화, D/SR/JK 플립플롭 | 조합 회로와 구분되는 피드백 언급 누락 |
| 래치 vs 플립플롭 구분 | 레벨 트리거 vs 엣지 트리거, 글리치 전파 차이 | 두 소자를 동의어로 취급 |
| 타이밍 제약과 CPU 적용 | 셋업/홀드 타임, 메타스테빌리티, 파이프라인 레지스터 | 1비트 동작만 쓰고 CPU 확장 사례 생략 |

> 요약: 피드백·클럭 기반의 1비트 저장 원리를 보이고, D 플립플롭→레지스터→파이프라인 버퍼→FSM으로의 확장을 연결해야 함.

## Ⅰ. 개요 및 필요성
- 개요: 조합 논리 회로에 기억 소자(플립플롭)를 추가해 현재 입력과 이전 상태가 함께 출력을 결정하는 동기식 회로임
- 배경: 조합 회로(028)는 연산만 가능하고 결과를 보존할 수 없어, 순차적 명령어 흐름(상태 천이)을 추적할 수 없음
- 필요성: 클럭에 맞춰 데이터를 정확한 타이밍에 캡처·보존하고 다음 연산기로 전달해 프로세서의 동기식 파이프라인을 구현함

## Ⅱ. 구조 및 구성요소
선형 구조도 (FSM 기본 구조):

    [입력] + [현재 상태 Q(t)] -> [조합 회로: 다음 상태 연산] -> [기억 소자: D 플립플롭(Clock)] -> [다음 상태 Q(t+1)] -> [출력]
                                                                        피드백 루프

| 기억 소자 | 동작 방식 | 주요 용도 |
|:---|:---|:---|
| SR 플립플롭 | Set(1)/Reset(0) 핀 제어, S=R=1 금지 | 원리 학습용 기본 소자 |
| D 플립플롭 | 클럭 엣지에서 D값 그대로 캡처(Q←D) | CPU 레지스터·파이프라인 버퍼 (현대 표준) |
| JK 플립플롭 | SR 금지 해결, J=K=1이면 Toggle | 카운터·주파수 분주기 |
| T 플립플롭 | 입력 1이면 현재 값 반전(Toggle) | 바이너리 카운터 |

> 요약: 현대 아키텍처는 타이밍 안전한 D 플립플롭을 병렬로 묶어 레지스터를 구성하고, JK/T는 카운터 등 특수 용도에 한정함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (D 플립플롭 엣지 트리거 동작):

    데이터 D 입력 -> [셋업 타임 확보: 엣지 전 안정] -> [클럭 Rising Edge] -> D값 캡처(Q 갱신) -> [홀드 타임 유지] -> 다음 엣지까지 Q 유지

1. 상태 대기: 클럭이 평탄한 구간에서는 D가 변해도 내부 상태 Q는 이전 값을 유지함
2. 셋업 타임 확보: 클럭 엣지 직전 최소 t_setup 동안 D 신호가 안정적으로 유지됨
3. 엣지 캡처: 클럭이 0→1로 상승하는 찰나(Rising Edge)에 게이트가 열려 현재 D를 피드백 루프에 확정함
4. 홀드 타임 유지: 엣지 직후 최소 t_hold 동안 D가 유지되어 캡처된 Q가 다음 클럭까지 안전하게 잠금됨

> 요약: 엣지 트리거는 찰나에만 문을 열어 글리치가 기억 소자에 잘못 저장되는 것을 완벽히 차단함.

## Ⅳ. 특징
- 동기식 제어: 시스템 전체에 동일 클럭(Clock Tree)을 분배해 수백만 플립플롭이 동시에 상태를 갱신함
- 상태 천이: 현재 상태 Q(t)와 입력 X의 조합으로 다음 상태 Q(t+1)이 기계적으로 결정되는 무어(Moore)/밀리(Mealy) FSM 모델 기반임
- 타이밍 제약: 클럭 주기가 조합 회로의 임계 경로 지연(Critical Path Delay) + 셋업 타임보다 짧으면 데이터 미도착으로 치명적 오류가 발생함
- SRAM 기반: 인버터 2개의 피드백 루프(래치 원리)로 6T SRAM 셀을 구성해 캐시 메모리(L1/L2)를 구현함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 래치 (Latch) | 플립플롭 (Flip-Flop) | 선택 기준 |
|:---|:---|:---|:---|
| 제어 방식 | 레벨 트리거 (High 구간 내내 열림) | 엣지 트리거 (변환 찰나에만 열림) | 안정성 요구 수준 |
| 노이즈 민감도 | 높음 (열린 동안 입력 변화 시 출력 튐) | 낮음 (찰나 캡처로 글리치 차단) | 신호 무결성 요구 |
| 게이트 수 | 적음 (면적 유리) | 많음 (안정성 우선) | 면적 vs 안정성 |
| 실무 적용 | 클럭 게이팅 등 비동기 특수 로직 | 거의 모든 동기식 레지스터·파이프라인 | 클럭 트리 유무 |

> 요약: 래치는 게이트 수가 적어 면적 유리하나 타이밍 위험이 커, 현대 CPU의 파이프라인 레지스터는 모두 엣지 트리거 플립플롭을 표준으로 사용함.

**리스크·대응:**
- 메타스테빌리티: 셋업/홀드 타임 위반 시 플립플롭이 0도 1도 아닌 중간 전압에 빠짐 → 클럭 도메인 교차(CDC) 시 더블 플립플롭(Synchronizer) 직렬 배치로 MTBF를 수십 년 이상 확보 (지표: MTBF > 10^9 시간)
- 클럭 스큐(Clock Skew): 배선 길이 차이로 플립플롭마다 클럭 도착 시간이 달라져 상태 갱신 엇박자 → H-Tree 클럭 분배망 + 버퍼 삽입으로 스큐를 피코초 단위로 통제 (지표: 스큐 < 1 클럭 주기의 5%)

**점검 지표:**
- 타이밍 클로저: 조합 회로 임계 경로 지연 + 셋업 타임 < 클럭 주기 — STA(Static Timing Analysis)로 검증
- 클럭 분배 균일성: Clock Tree의 스큐·지터가 허용 범위 내인지 — 실리콘 측정·시뮬레이션

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. CPU 파이프라인 레지스터: IF-ID-EX-MEM-WB 각 스테이지 사이에 D 플립플롭 다발을 배치해 앞 단계 결과를 엣지에 맞춰 캡처하고 뒷단으로 안정 전달함
2. 프로그램 카운터·타이머: JK/T 플립플롭 기반 동기식 카운터로 매 클럭마다 메모리 주소를 자동 증가시키고, 분기 명령어 시 목표 주소를 로드함
3. 초고속 SRAM 캐시: 인버터 2개의 피드백 래치(6T 셀)로 L1/L2 캐시를 구성해 재충전(Refresh) 없이 DRAM 대비 5~10배 빠른 접근 속도를 확보함

**결론:**
- 기술사 판단: 순서 논리 회로는 조합 논리의 연산 결과를 클럭 엣지에 맞춰 보존하는 상태 관리의 본질이며, 셋업/홀드 타임과 클럭 스큐 통제(Timing Closure)가 프로세서 동작 주파수의 상한을 결정함
- 향후 방향: 클럭 트리가 전체 전력의 30% 이상을 소모하는 병목이 됨에 따라, 핸드셰이킹 기반 비동기식(Asynchronous) 순서 논리 설계와 Razor 플립플롭(타이밍 에러 감지·복구) 연구가 확대되고 있음
