## 미리 알고가기

- 순서 논리: 현재 입력과 저장된 이전 상태를 함께 사용해 출력을 결정하는 회로임
- 래치: 클럭 에지가 아니라 enable 신호가 활성인 동안 입력을 통과시키는 기억 소자임
- 플립플롭: 클럭 에지에서 입력을 샘플링해 1비트 상태를 저장하는 소자임
- 레지스터: 여러 플립플롭을 묶어 다비트 데이터를 저장하는 회로임
- FSM: 상태와 입력에 따라 다음 상태와 출력을 정의하는 유한 상태 기계임

## Ⅰ. 개요

- **정의**: 순서 논리 회로는 기억 소자에 저장된 이전 상태와 현재 입력을 함께 사용해 다음 상태와 출력을 결정하는 디지털 회로임
- **배경/필요성**: CPU 명령 실행, 카운터, 프로토콜 제어, 레지스터 파일은 시간 순서와 상태 유지가 필요하므로 클럭 동기화와 상태 전이 설계가 필수임.
- **비유**: 현재 주문뿐 아니라 이전 단계의 처리 상태를 기억해 다음 작업을 결정하는 업무 프로세스와 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 순서 논리 구조 설명 | 플립플롭, 클럭, 상태, 피드백 | 조합 논리와 구분 누락 |
| 동기 회로 위험 이해 | setup/hold, metastability, FSM | 단순 저장 회로로만 설명 |

> 요약: 순서 논리는 상태를 저장하고 클럭에 맞춰 갱신함으로써 시간 순서가 있는 연산과 제어를 가능하게 하는 회로임.

## Ⅱ. 특징/비교

| 판단 기준 | 조합 논리 회로 | 순서 논리 회로 |
|:---|:---|:---|
| 출력 근거 | 현재 입력만으로 결정됨 | 현재 입력과 저장 상태로 결정됨 |
| 핵심 소자 | 게이트, MUX, 가산기 중심임 | 래치, 플립플롭, 레지스터 중심임 |
| 시간 개념 | 전파 지연만 고려함 | 클럭 주기, setup/hold, 상태 전이를 고려함 |
| 선택 기준 | 즉시 계산이 필요할 때 적합함 | 기억, 카운팅, 순차 제어가 필요할 때 적합함 |

- **동기 기준**: 대부분의 시스템은 클럭 에지를 기준으로 상태를 동시에 갱신해 예측성을 확보함.
- **상태 기준**: FSM은 상태 수와 전이 조건을 명확히 해야 검증 가능한 제어가 됨.
- **타이밍 기준**: setup/hold 위반은 기능 논리식이 맞아도 실제 칩에서 오류를 만들 수 있음.

> 요약: 순서 논리는 저장 상태와 클럭 타이밍을 함께 설계해야 하며, 기능 검증과 타이밍 검증이 동시에 필요함.

## Ⅲ. 구성요소

```text
+------------+      +------------+      +------------+
| Inputs     | ---> | Next State | ---> | Flip-Flop  |
| and State  |      | Logic      |      | Register   |
+------------+      +------------+      +------------+
       ^                                      |
       |                                      v
+------------+      +------------+      +------------+
| Feedback   | <--- | Current    | <--- | Clock      |
| Path       |      | State      |      | Edge       |
+------------+      +------------+      +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 플립플롭 | 클럭 에지에서 1비트 입력을 저장하고 다음 주기까지 유지함 | 잠금식 메모 칸 |
| 레지스터 | 여러 플립플롭으로 n비트 값을 동시에 저장함 | 데이터 보관함 한 줄 |
| 다음 상태 논리 | 현재 상태와 입력을 조합해 다음 상태 값을 계산함 | 다음 업무 결정 규칙 |
| 클럭 | 상태 갱신 시점을 맞추는 주기 신호임 | 박자 신호 |
| 피드백 경로 | 저장된 현재 상태를 다시 입력으로 되돌려 순차 동작을 만듦 | 이전 기록 참조 |

> 요약: 순서 논리는 다음 상태 논리가 값을 계산하고 플립플롭이 클럭에 맞춰 저장하며, 저장 상태가 다시 제어 입력으로 돌아오는 구조임.

## Ⅳ. 절차

```text
+------------+      +------------+      +------------+      +------------+
| Define     | ---> | Encode     | ---> | Design     | ---> | Verify     |
| States     |      | State Bits |      | FF Logic   |      | Timing     |
+------------+      +------------+      +------------+      +------------+
```

1. **상태 정의**: 회로가 기억해야 할 상태와 입력 조건, 출력 조건을 정의함.
2. **상태 인코딩**: 상태를 플립플롭 비트 패턴으로 배정하고 초기 상태를 정함.
3. **전이 논리 설계**: 다음 상태 함수와 출력 함수를 조합 논리로 구현함.
4. **타이밍 검증**: 클럭 주기, setup/hold, reset, metastability 위험을 확인함.

> 요약: 순서 회로 설계는 상태를 정의하고 비트로 인코딩한 뒤 전이 논리와 타이밍 조건을 검증하는 과정임.

## Ⅴ. 문제점

- **P1 타이밍 위반**: setup/hold 시간이 지켜지지 않으면 플립플롭이 잘못된 값을 저장하거나 불안정 상태에 빠질 수 있음.
- **P2 상태 폭발**: 제어 조건이 많아지면 FSM 상태와 전이 수가 증가해 설계와 검증이 어려워짐.
- **P3 클럭 도메인 문제**: 서로 다른 클럭 영역 사이 신호 전달은 metastability와 데이터 손실을 일으킬 수 있음.

> 요약: 순서 논리의 핵심 문제는 타이밍 조건, 상태 규모, 클럭 경계에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: static timing analysis, 클럭 여유 확보, 파이프라이닝으로 setup/hold 위반을 제거함. (확인: timing slack)
- **P2 대응**: FSM 상태 최소화, 계층형 FSM, 명확한 상태 전이표로 검증 범위를 줄임. (확인: 상태 수와 전이 커버리지)
- **P3 대응**: 2단 동기화 플립플롭, FIFO, handshake 프로토콜로 클럭 도메인 crossing을 처리함. (확인: CDC 분석)

> 요약: 순서 논리는 타이밍 분석, FSM 구조화, CDC 대응으로 setup/hold 위반과 metastability로 인한 오동작을 차단해야 함.

## Ⅶ. 전망

- **발전 방향**: 고성능 CPU, SoC, FPGA 설계에서 파이프라인과 클럭 도메인 관리는 더 복잡해질 전망임.
- **기술사적 판단**: 기능 논리보다 상태 전이와 setup/hold 충족 여부가 시스템 장애를 좌우하므로 검증 계획에 우선 반영해야 함.
- **기술사 제언**: 답안에서는 조합 논리와 대비한 뒤 플립플롭, FSM, 타이밍 문제를 한 흐름으로 설명해야 함.
