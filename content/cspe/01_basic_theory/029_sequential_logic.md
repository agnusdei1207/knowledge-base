# 📖 【암기용】 개념 완전 이해

> 목적: 순서 논리 회로를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 현재 입력과 저장된 과거 상태로 출력이 결정되는 디지털 회로
- **왜 필요한가**: CPU는 명령어 진행, 레지스터 값, 카운터, FSM 상태처럼 시간에 따라 변하는 정보를 저장해야 한다.
- **핵심 직관**: 조합 논리가 계산기라면 순서 논리는 계산기에 메모장을 붙인 구조이다.

## 깊이 이해
- **배경·문제의식**: 입력만으로 출력이 정해지는 회로는 "이전 상태"를 표현하지 못함
- **적용 사례**: 프로세서 제어, 통신 프로토콜, 메모리 주소 순서는 상태 저장이 필요함
- **작동 원리**: 플립플롭은 클럭 엣지에서 D 입력을 Q로 저장함
- **구성 확장**: 여러 플립플롭을 묶으면 레지스터가 되고, 조합 논리와 결합하면 FSM이 됨
- **비유**: 엘리베이터 제어기는 현재 버튼뿐 아니라 현재 층과 이동 방향을 기억해야 다음 동작을 결정한다.
- **구체 예시**: 32비트 레지스터는 D 플립플롭 32개로 구성되며, 클럭 상승 엣지에서 32비트 값을 동시에 저장한다.
- **흔한 오해·주의점**: 클럭만 맞추면 충분하지 않음
- **타이밍 조건**: 입력은 setup time 전에 도착하고 hold time 동안 유지되어야 하며, 위반 시 metastability가 발생할 수 있음

## 연결 개념
- 조합 논리 회로 — next-state logic과 output logic 구성
- 파이프라인 레지스터 — CPU stage 사이 상태 보존
- FSM — 순서 논리의 대표적 제어 모델


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 순서 논리 회로는 저장 요소와 조합 논리를 결합해 입력 이력에 따른 상태 전이를 구현한다.
> 2. **가치**: 플립플롭·레지스터·카운터·FSM으로 CPU 제어 흐름과 데이터 보존을 가능하게 한다.
> 3. **판단 포인트**: 클럭, setup/hold time, 상태 전이, reset 정책, metastability 대응을 함께 설계해야 한다.


## Ⅰ. 개요 및 필요성

- 개요: 순서 논리 회로는 상태를 저장하는 디지털 회로임
- 배경: 디지털 시스템은 현재 입력뿐 아니라 이전 상태에 따라 다음 동작을 결정해야 함
- 필요성: 플립플롭과 레지스터는 클럭 기준 상태 저장을 제공해 CPU, 버스, 제어기의 기반이 됨


## Ⅱ. 구조 및 구성요소

```text
현재 상태 Q + 입력 X -> 조합 논리 -> 다음 상태 D
Clock edge -> 플립플롭/레지스터 -> 현재 상태 Q 갱신
Reset -> 초기 상태 지정
```

| 구성요소 | 역할 | 수치·조건 |
|:---|:---|:---|
| 플립플롭(Flip-Flop) | 1비트 상태 저장 | D FF 1개=1비트 |
| 레지스터(Register) | 다비트 데이터 저장 | 32비트=FF 32개 |
| 조합 논리 | 다음 상태와 출력 계산 | next-state/output logic |
| 클럭·리셋 | 저장 시점과 초기 상태 제어 | setup/hold, sync/async reset |

> 요약: 순서 논리는 조합 논리와 플립플롭 피드백으로 현재 상태를 저장하고 다음 상태를 계산한다.


## Ⅲ. 동작원리 및 흐름도

```text
입력 X + 현재상태 S -> 다음상태 계산 -> 클럭 엣지 대기
-> setup/hold 만족 -> 플립플롭 저장 -> 출력 Q 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 현재 상태 Q와 입력 X를 조합 논리에 전달 | fan-out, 입력 도착 시간 |
| 2 | 다음 상태 D 계산 | propagation delay |
| 3 | 클럭 엣지 전후 타이밍 조건 확인 | setup time, hold time |
| 4 | 플립플롭 저장 후 출력 Q 갱신 | clock-to-Q delay |

> 요약: 순서 논리는 클럭 엣지에서 상태를 저장하므로 조합 지연, setup/hold, clock-to-Q를 합산해 타이밍을 검증한다.


## Ⅳ. 특징

| 구분 | 조합 논리 회로 | 순서 논리 회로 | 판단 포인트 |
|:---|:---|:---|:---|
| 저장 요소 | 없음 | Flip-Flop, Latch, Register | 상태 보존 가능 |
| 출력 결정 | 현재 입력 | 현재 입력 + 현재 상태 | FSM 모델링 |
| 시간 제약 | propagation delay | setup/hold, clock skew | STA 필수 |
| 대표 위험 | glitch | metastability, race | 동기화 회로 필요 |

> 요약: 순서 논리는 상태 기반 제어에 필수이며, 클럭 도메인과 타이밍 조건 위반을 설계 단계에서 통제해야 한다.


## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 조합 논리 | 순서 논리 | 상태·이력·클럭 기준 저장 필요 |
| 비용/성능 | binary encoding | one-hot FSM | 상태 수 8개 이하, 속도 우선 시 |
| 운영/위험 | 단일 클럭 가정 | CDC·reset·STA 관리 | 다중 클럭·비동기 입력 존재 시 |

> 요약: 순서 논리는 상태 저장이 필요할 때 선택하며, 클럭 경계와 reset 정책이 설계 품질을 좌우함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| metastability | 비동기 입력·CDC | 2단 동기화 FF, async FIFO | CDC violation 0건 |
| setup/hold 위반 | 조합 지연·clock skew | STA, retiming, pipeline | slack 0ns 이상 |
| reset 불일치 | sync/async 혼용 | reset-domain crossing 분석 | RDC warning 0건 |

> 요약: 순서 회로 리스크는 CDC, 타이밍, reset이며 STA·CDC·RDC 점검으로 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 타이밍 | setup/hold slack 0ns 이상 | STA |
| 상태 검증 | FSM unreachable state 0건 | formal verification |
| CDC 품질 | CDC violation 0건 | CDC lint |

> 요약: 순서 논리 적용 품질은 STA slack, FSM 검증, CDC lint 결과로 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 레지스터 설계: 64비트 데이터 경로는 D FF 64개와 enable 신호로 구성, reset 값 명시
2. FSM 구현: 상태 수 8개 이하면 one-hot, 면적 제약이 크면 binary encoding 적용
3. CDC 대응: 다른 클럭 도메인 입력은 2단 동기화 플립플롭 또는 async FIFO 사용

**결론 (2줄):**
- 기술사 판단: 단일 클럭 제어는 D FF 기반 동기식 설계, 다중 클럭 경계는 CDC 분석과 동기화 회로를 우선 적용함
- 향후 방향: SoC 검증은 STA, CDC lint, reset-domain crossing 분석을 통합해 상태 오류를 사전 탐지함
