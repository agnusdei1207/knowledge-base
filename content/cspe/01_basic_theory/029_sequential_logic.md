## 미리 알고가기

- 클록: 상태 갱신 시점을 맞추는 기준 신호임
- 래치/플립플롭: 1비트 상태를 저장하는 기억 소자임
- setup/hold time: 데이터가 안정적으로 저장되기 위한 시간 조건임

## Ⅰ. 개요

- **정의/개념**: 순서 논리 회로는 현재 입력뿐 아니라 이전 상태를 함께 사용해 출력을 결정하는 회로로, 플립플롭과 레지스터가 상태 저장의 기본 요소임
- **배경/필요성**: 카운터, 상태기계, 파이프라인처럼 과거 값과 순서를 기억해야 하는 시스템은 조합 논리만으로 구현할 수 없음

## Ⅱ. 특징

- 내부 상태를 저장해 시간 축을 가진 동작을 구현함
- 클록 기반 설계로 복잡한 제어를 안정적으로 동기화할 수 있음
- 성능은 조합 경로뿐 아니라 setup, hold, skew에 의해 제한됨
- 비동기 입력이 직접 들어오면 메타안정성 문제가 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 조합 논리 | 순서 논리 |
|:---|:---|:---|
| 출력 결정 요소 | 현재 입력만 | 현재 입력 + 이전 상태 |
| 기억 기능 | 없음 | 있음 |
| 대표 소자 | 가산기, MUX | 플립플롭, 레지스터, 카운터 |
| 대표 용도 | 즉시 연산 | 제어, 저장, 상태 전이 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 플립플롭 | 1비트 상태를 저장하고 상태기의 최소 단위임 |
| 조합 논리 블록 | 다음 상태와 출력을 계산하고 동작 규칙을 정의함 |
| 클록 네트워크 | 상태 갱신 시점을 맞춤 타이밍 품질을 좌우함 |
| 리셋 회로 | 초기 상태를 강제하고 부팅 안정성 확보 요소임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 입력수신 | --> | 다음상태 계산 | --> | 클록에지 대기 | --> | 상태갱신 |
+----------+     +----------+     +----------+     +----------+
```

1. **입력수신**: 현재 입력과 기존 상태를 읽음
2. **다음상태 계산**: 조합 논리로 다음 상태와 출력을 계산함
3. **클록에지 대기**: 지정된 엣지에서만 상태 갱신을 허용함
4. **상태갱신**: 플립플롭이 새 값을 저장함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 타이밍 위반이 발생해 setup/hold 조건이 깨지면 오동작함
   - 해결방안: 클록 주기 조정, 파이프라인, 경로 최적화를 수행하고 slack로 검증함
2. 문제: 메타안정성이 생겨 비동기 입력이 경계 시점에 들어오면 상태가 불안정함
   - 해결방안: 2단 동기화기와 CDC 검증을 적용하고 MTBF로 검증함
3. 문제: 리셋 전략이 부실하면 초기화 불량이 생겨 시스템 부팅 상태가 불확실해짐
   - 해결방안: 동기/비동기 리셋 정책을 분리하고 검증하고 부팅 성공률로 검증함

## Ⅶ. 적용 사례

- CPU 파이프라인 레지스터에서는 단계 간 데이터를 저장함, 확인 지표는 최대 클록 주파수임
- 통신 제어 FSM에서는 패킷 처리 상태를 전이함, 확인 지표는 상태 전이 오류율임
- 임베디드 카운터/타이머에서는 주기 이벤트를 생성함, 확인 지표는 시간 정확도임

## Ⅷ. 결론

순서 논리 회로는 상태 저장이 핵심이므로, 기능 설계보다 타이밍과 동기화 품질을 먼저 통제해야 안정적인 시스템이 됨.
