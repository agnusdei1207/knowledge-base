## 미리 알고가기

- **래치(Latch) vs 플립플롭(Flip-Flop)**: 래치는 신호의 레벨(0 또는 1 상태 유지 시)에 따라 반응하며, 플립플롭은 클럭의 엣지(0에서 1로 변하는 순간 등)에 반응하여 상태를 갱신함
- **준안정 상태(Metastability)**: 입력 신호가 클럭 엣지와 너무 가깝게 변하여 플립플롭 출력이 0도 1도 아닌 불안정한 상태로 유지되는 현상. 시스템 오동작의 주원인임
- **Setup/Hold Time**: 클럭 엣지 전후로 입력 데이터가 안정적으로 유지되어야 하는 최소 시간. 이 조건을 위반하면 데이터 저장에 실패함

## Ⅰ. 개요

- **정의/개념**: 순서 논리 회로(Sequential Logic Circuit)는 현재의 입력값뿐만 아니라 회로 내부에 저장된 이전 상태(State)를 함께 고려하여 출력을 결정하는 논리 회로임. 메모리 요소(플립플롭 등)와 조합 논리가 피드백 구조로 결합되어 시간에 따른 상태 변화를 추적함
- **배경/필요성**: 가산기 같은 조합 논리는 '지금 무엇인가'에 답하지만, '이전에 무엇이었는가'를 기억하지 못함. CPU의 명령어 처리 단계(Fetch-Decode-Execute), 신호등 제어의 상태 전이, 데이터를 일시 보관하는 레지스터 등 '시간의 흐름'과 '과거의 이력'이 필요한 모든 기능은 순서 논리를 통해 구현됨. 따라서 안정적인 데이터 보관과 클럭 박자에 맞춘 질서 있는 상태 전이를 위해 순서 논리 설계가 필수적임

## Ⅱ. 특징 및 비교

### 가. Moore 머신과 Mealy 머신의 구조적 차이

| 구분 | Moore 머신 (Moore Machine) | Mealy 머신 (Mealy Machine) |
|:---|:---|:---|
| 출력 결정 요인 | 오직 현재의 상태(State)에만 의존 | 현재 상태 + 현재 입력에 의존 |
| 출력 변화 시점 | 클럭 엣지에서 상태가 바뀔 때만 | 입력이 바뀌면 즉시 바뀔 수 있음 |
| 설계 복잡도 | 상태 수가 많아질 수 있으나 설계가 명확함 | 상태 수는 적으나 타이밍 분석이 까다로움 |
| 응용 분야 | 제어기 설계, 안정성이 중시되는 시스템 | 빠른 응답성이 요구되는 프로토콜 처리 |

> 요약: Moore 머신은 상태 중심의 안정적 출력을, Mealy 머신은 입력에 즉각 반응하는 빠른 출력을 제공함

### 나. 순서 논리의 핵심 메커니즘
- **상태 기억**: 플립플롭을 통해 1비트 정보를 유지하며, 이를 병렬로 묶어 n비트 레지스터 구성
- **피드백 루프**: 현재 상태값이 다음 상태를 결정하는 조합 논리의 입력으로 다시 환환되는 구조
- **동기화(Synchronization)**: 시스템 전체가 동일한 클럭 신호에 맞춰 일사불란하게 상태를 갱신

## Ⅲ. 구성요소/구조

### 가. 순서 논리 회로의 기본 아키텍처

```text
       +---------------------------------------------+
       |                                             |
[입력]--+--> [다음 상태 논리] ----> [플립플롭/레지스터] --+--> [현재 상태]
             (조합 논리)            (기억 소자)             |
                                      ^                    |
                                      |                    |
                                   [클럭] ------------------+--> [출력 논리] --> [출력]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 기능 | 핵심 포인트 |
|:---|:---|:---|
| 플립플롭 (Flip-Flop) | 클럭 엣지에서 입력 데이터를 샘플링하여 저장 | RS, D, JK, T 등 다양한 유형 존재 |
| 레지스터 (Register) | 플립플롭의 집합체로 n비트 데이터 일시 보관 | CPU 내부의 연산 데이터 저장소 |
| 클럭 (System Clock) | 시스템 전체의 타이밍을 제어하는 주기적 신호 | 주파수가 높을수록 처리 속도 증가 |
| 다음 상태 논리 | 현재 상태와 입력을 조합해 다음 갈 곳을 계산 | 진리표 대신 상태 전이표 활용 |
| 상태 전이도 (STG) | 상태 간의 이동 경로를 시각화한 설계도 | 누락된 상태나 교착 상태 여부 확인 |

> 요약: 조합 논리가 '판단'을 하고, 플립플롭이 그 결과를 클럭에 맞춰 '기억'하는 순환 구조임

## Ⅳ. 문제점 및 개선방안

1. **클럭 스큐(Clock Skew)**: 클럭 신호가 각 플립플롭에 도착하는 시간이 배선 길이에 따라 미세하게 달라져 동기화가 깨지는 현상
   - **개선방안**: 클럭 트리 합성(CTS, Clock Tree Synthesis) 기법을 통해 모든 경로의 클럭 지연을 균일하게 맞추고 클럭 버퍼를 적절히 배치함

2. **Setup/Hold Time 위반**: 조합 논리의 지연이 너무 길어 클럭 엣지 전에 데이터가 안정되지 않거나, 데이터가 너무 일찍 변하여 저장에 실패함
   - **개선방안**: 지연이 긴 경로를 쪼개는 파이프라이닝(Pipelining)을 적용하거나, 클럭 주기를 늘려 타이밍 마진을 확보함

3. **준안정 상태로 인한 연쇄 오동작**: 비동기 입력이 클럭과 겹쳐 출력이 진동함
   - **개선방안**: 2단 이상의 플립플롭을 직렬 연결하는 동기화기(Synchronizer)를 사용하여 신호가 정상 레벨로 수렴할 시간을 벌어줌

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 마이크로프로세서 제어부 | 명령어 실행 단계를 상태 머신(FSM)으로 설계하여 순차 제어 | 명령어 당 사이클 수(CPI), 분기 예측 정확도 |
| 네트워크 패킷 처리 | 패킷 헤더의 상태를 추적하며 필터링 및 포워딩 결정 | 패킷 처리 지연(Latency), 처리량(Throughput) |
| 시퀀스 제어 (PLC) | 산업 현장의 공정 순서를 순차적으로 제어하고 상태 기록 | 공정 주기 시간, 예외 상황 복구 성공률 |

> 요약: 복잡한 순차적 흐름을 가진 모든 지능형 시스템은 정교하게 설계된 순서 논리의 집합체임

## Ⅵ. 결론

순서 논리 회로는 디지털 시스템에 '시간'과 '기억'이라는 차원을 부여하여 단순 계산기를 넘어선 복잡한 지능형 시스템을 가능하게 함. 설계의 성공 여부는 단순한 논리적 정합성을 넘어, 나노초(ns) 단위의 정교한 타이밍 제어와 클럭 동기화의 안정성을 확보하는 데 달려 있음.

기술사는 시스템 설계 시 Moore/Mealy 모델 중 적합한 방식을 선택하고, STA(Static Timing Analysis) 도구를 통해 타이밍 위반 가능성을 사전에 차단하며, 준안정 상태와 클럭 스큐 같은 물리적 제약 조건을 해결할 수 있는 설계 역량을 갖추어야 함.
