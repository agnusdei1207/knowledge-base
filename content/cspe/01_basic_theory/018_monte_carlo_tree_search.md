# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: MCTS는 **무작위 시뮬레이션(몬테카를로 방법, 017 참조)을 트리 탐색에 결합**해, 방대한 게임·의사결정 트리에서 각 수의 가치를 시뮬레이션 승률로 추정하며 **유망한 가지를 점진적으로 깊게 파는** 최선우선 탐색 알고리즘이다.
- **왜 필요한가**: 바둑(경우의 수 약 10^170)처럼 트리가 거대하면 미니맥스 완전 탐색이 불가능하고 정확한 평가 함수도 만들기 어려우므로, **완전 전개 없이 표본 시뮬레이션 통계로 유망한 수만 선택적으로 탐색**하기 위해서다.
- **핵심 직관**: "**해보고(시뮬레이션) 좋았던 수를 더 파되(활용), 덜 시도한 수도 가끔 열어 본다(탐색)**" — Selection→Expansion→Simulation→Backpropagation 4단계를 반복하며 트리를 비대칭으로 키운다.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안용 Ⅰ~Ⅵ·표에 나오는 MCTS 고유 표기를 비유와 함께 먼저 세운다(난수 추정 일반은 017, 트리·DFS는 008·010 참조). 맨 위는 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| MCTS (상위 키워드) | 무작위 시뮬레이션 통계로 유망 가지를 키우는 최선우선 트리 탐색 | 유망한 수만 골라 여러 번 시뮬레이션 |
| 선택 (Selection) | 루트에서 UCT 최댓값 자식을 따라 잎까지 내려감 | 승률 높은 갈래를 따라 내려가기 |
| 확장 (Expansion) | 도달한 잎에 아직 안 둔 수를 자식 노드로 추가 | 새 수 하나를 트리에 붙임 |
| 시뮬레이션 (Simulation/Playout) | 새 노드부터 게임 끝까지 무작위로 진행해 승패 확인 | 대충 끝까지 둬 보고 이겼는지 봄 |
| 역전파 (Backpropagation) | 시뮬레이션 결과를 경로상 모든 노드에 갱신 | 결과를 위로 되짚어 승률 반영 |
| UCT (UCB1 for Trees) | 활용(승률)+탐색(방문 적을수록 가산) 균형 선택식 | 좋은 수와 안 해본 수를 저울질 |
| 활용-탐색 균형 (Exploit-Explore) | 좋은 수 심화 vs 미탐색 수 개척의 절충 | 맛집 재방문 vs 새 집 시도 |
| 비대칭 트리 성장 | 유망 가지만 깊게 자라는 불균형 확장 | 승산 있는 방향만 깊이 파고듦 |

## 깊이 이해
- **배경·문제의식**: 바둑·복잡 게임은 상태공간이 천문학적이라 미니맥스로 전개할 수 없고, 좋은 휴리스틱 평가 함수 설계도 어렵다. MCTS는 **평가 함수 없이 무작위 대국 결과 통계**로 수의 가치를 추정해 이 두 난점을 동시에 우회한다.
- **작동 원리 (어떻게+왜)**:
  - **4단계 루프**: ① Selection — 루트에서 UCT가 큰 자식을 따라 잎까지 하강, ② Expansion — 잎에 새 수 자식 추가, ③ Simulation — 그 노드부터 종국까지 무작위 진행해 승/패 산출, ④ Backpropagation — 결과를 경로 전체 방문수·승수에 반영. 이 루프를 시간·횟수 예산까지 반복한다.
  - **UCT가 균형을 잡는 이유**: UCT = (자식 평균 승률) + C·√(ln N_부모 / n_자식). 첫 항은 **활용**(승률 높은 수 선호), 둘째 항은 **탐색**(방문 적은 수에 가산)으로, 유망하되 덜 검증된 수도 열어 국소 최적 함정을 피한다.
  - **왜 완전 탐색이 필요 없나**: 시뮬레이션 통계가 나쁜 가지의 승률을 낮춰 자연히 방문이 줄고, 좋은 가지에 예산이 몰려 트리가 비대칭으로 자란다. 즉 유망 영역만 정밀 탐색한다.
  - **017과의 관계·차별점**: 017은 난수 표본으로 값을 추정하는 **일반 원리**, MCTS는 그 무작위 시뮬레이션을 **트리의 각 수 가치 추정과 선택적 확장**에 응용한 특화 탐색이다.
- **비유**: 낯선 도시에서 맛집을 찾을 때, 지금까지 만족도가 높던 거리를 다시 가되(활용) 아직 안 가 본 골목도 가끔 들러(탐색), 다녀온 만족도를 지도에 계속 갱신해 점점 좋은 구역에 방문을 집중한다.
- **구체 예시(수치·사례)**: 알파고는 MCTS에 정책·가치 신경망을 결합해, 무작위 playout 대신 신경망이 유망 수와 승률을 안내하도록 하여 인간 최고수를 이겼다. 순수 MCTS도 바둑·체스·장기·틱택토, 실시간 전략 게임 AI, 조합 최적화·스케줄링에 쓰인다.
- **흔한 오해·주의점**:
  - **"MCTS = 몬테카를로 방법"이라는 오해** — 017은 난수 추정 일반, MCTS는 그것을 트리 탐색·선택적 확장에 응용한 알고리즘이다.
  - **랜덤 playout이 항상 충분하다는 오해** — 순수 무작위 시뮬레이션은 수렴이 느려, 알파고처럼 신경망·도메인 휴리스틱으로 안내해야 강해진다.
  - **애니타임 특성 간과** — MCTS는 언제 멈춰도 그때까지 최선 수를 내는 애니타임 알고리즘으로, 시간 예산에 맞춰 품질이 오른다.

## 연결 개념
- **몬테카를로 방법 (017)**: MCTS의 시뮬레이션 단계가 사용하는 무작위 표본 추정의 상위 일반 원리.
- **트리·그래프 탐색 (008·010)**: MCTS가 확장·순회하는 상태 트리와 최선우선 탐색의 구조적 토대.
- **강화학습·신경망 (058·048)**: 알파고처럼 정책·가치망으로 선택·시뮬레이션을 안내해 MCTS를 강화하는 결합 확장.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCTS는 무작위 시뮬레이션 통계로 수의 가치를 추정하며 유망 가지를 비대칭으로 키우는 최선우선 트리 탐색임.
> 2. **가치**: 평가 함수 없이 Selection-Expansion-Simulation-Backpropagation 4단계와 UCT로 거대 트리(바둑 10^170)를 선택적으로 탐색함.
> 3. **판단 포인트**: 활용-탐색 균형(UCT의 C)이 성능을 좌우하며, 순수 playout은 수렴이 느려 신경망·휴리스틱 안내로 강화해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MCTS 4단계 원리 | Selection·Expansion·Simulation·Backpropagation | 몬테카를로 방법(017)과 동일시 |
| UCT·균형 이해 | 활용+탐색 항의 절충, 비대칭 성장 | 활용-탐색 균형 설명 누락 |
| 응용·강화 | 바둑·게임 AI, 신경망 결합(알파고) | 순수 playout이 항상 충분하다고 단정 |

> 요약: 4단계 루프와 UCT 활용-탐색 균형·비대칭 성장, 신경망 결합 강화와 애니타임 특성을 짚어야 하며 017과 구분해야 함.

## Ⅰ. 개요 및 필요성
- 개요: 무작위 시뮬레이션 통계로 수 가치를 추정하며 유망 가지를 키우는 최선우선 트리 탐색임
- 배경: 바둑 등 상태공간이 천문학적(약 10^170)이라 미니맥스 완전 탐색과 정확한 평가 함수가 비현실적임
- 필요성: 완전 전개 없이 표본 시뮬레이션으로 유망 수만 선택적으로 정밀 탐색할 필요가 있음
- 차별성: 난수 추정 일반(017)과 달리 그 시뮬레이션을 트리의 수 선택·확장에 특화 응용함

## Ⅱ. 구조 및 구성요소
선형 구조도 (4단계 반복 루프):

    루트 노드 -> 선택(UCT 최대 자식으로 잎까지 하강) -> 확장(잎에 미시도 수 자식 추가) -> 시뮬레이션(새 노드부터 종국까지 무작위 진행) -> 역전파(경로 노드에 방문수·승수 갱신) -> 예산 소진까지 반복 -> 루트 최다 방문 수 선택
      / 예산 남음 : 다시 선택 단계로 순환
      / 예산 소진 : 방문수 최대(또는 최고 승률) 수를 최종 착수로 결정

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 선택(UCT) | 활용+탐색 균형으로 잎까지 경로 결정 | 상수 C가 탐색 강도 조절 |
| 확장 | 잎에 새 수 노드 추가 | 트리를 비대칭으로 성장 |
| 시뮬레이션 | 종국까지 무작위/안내 진행해 승패 산출 | 신경망·휴리스틱 안내 가능 |
| 역전파 | 결과를 경로 통계에 반영 | 방문수·누적 승수 갱신 |

> 요약: 선택·확장·시뮬레이션·역전파 4요소가 순환하며 UCT 균형으로 유망 가지를 비대칭 성장시켜 최다 방문 수를 착수로 결정함.

## Ⅲ. 동작원리 및 흐름도
선형 흐름도 (한 반복 기준):

    루트에서 UCT 최대 자식 따라 잎 도달 -> 잎에 새 수 노드 확장 -> 그 노드부터 무작위 대국 종국까지 진행 -> 승/패 결과 획득 -> 경로상 모든 노드 방문수·승수 갱신 -> 예산 확인 후 반복

1. 선택: 알고리즘이 루트부터 각 노드에서 UCT가 최대인 자식을 따라 미확장 잎까지 하강함
2. 확장: 알고리즘이 그 잎에 아직 시도 안 한 수를 새 자식 노드로 추가함
3. 시뮬레이션: 알고리즘이 새 노드 상태부터 종국까지 무작위(또는 정책망 안내)로 진행해 승패를 산출함
4. 역전파: 알고리즘이 승패 결과를 방금 지나온 경로의 모든 노드에 누적해 방문수·승률을 갱신함

> 요약: UCT로 잎까지 선택·확장 후 종국까지 시뮬레이션하고 결과를 경로에 역전파하며, 예산 소진 시 루트 최다 방문 수를 착수함.

## Ⅳ. 특징
- 평가 함수 불요: 무작위 시뮬레이션 승률로 수 가치를 추정해 정교한 휴리스틱 평가 함수 없이 동작함
- 애니타임 특성: 언제 중단해도 그때까지 최선 수를 반환하며 시간·횟수 예산에 비례해 품질이 향상됨
- 비대칭 선택 성장: UCT가 유망 가지에 방문을 몰아 트리를 불균형하게 깊이 키워 탐색량을 절약함
- 활용-탐색 균형: UCT의 상수 C로 좋은 수 심화와 미탐색 수 개척의 절충을 조절함
- 도메인 독립·확장성: 규칙만 알면 다양한 게임·의사결정에 적용되며 신경망 안내로 성능을 크게 높임

## Ⅴ. 심화 비교 및 적용 판단

게임 트리 탐색 계열을 탐색 방식·평가 방법·확장성 축에서 대조함(무작위 추정 일반은 017 참조).

| 구분 | MCTS | 미니맥스+알파베타 가지치기 | 순수 몬테카를로 시뮬레이션 |
|:---|:---|:---|:---|
| 탐색 방식 | 시뮬레이션 통계 기반 최선우선·선택적 확장 | 깊이 제한 전개 + 알파베타 가지치기 | 각 수를 독립 무작위 시행만 |
| 평가 방법 | playout 승률(평가 함수 불요) | 휴리스틱 평가 함수 필수 | 시행 평균 승률 |
| 트리 활용 | 통계 누적·비대칭 트리 성장 | 트리 없이 회차별 독립 추정 | 트리 성장 O(선택적) |
| 확장성 | 거대 상태공간(바둑)에 강함 | 분기수 큰 게임에 약함 | 얕은 판단에 한정 |

> 요약: MCTS는 트리에 시뮬레이션 통계를 누적해 평가 함수 없이 거대 트리를 다루고, 미니맥스는 평가 함수와 알파베타로 얕은 트리에 강함.

**리스크·대응:**
- 느린 순수 playout — 무작위 시뮬레이션 수렴이 느림 → 정책·가치 신경망·도메인 휴리스틱으로 안내
- 균형 상수 오설정 — C가 크면 산만·작으면 국소 최적 → 문제별 C 튜닝·PUCT 등 변형 채택
- 시뮬레이션 편향 — 비현실적 무작위 대국이 승률 왜곡 → 경량 정책·전개 정책 개선

**점검 지표:**
- 탐색 효율 — 동일 시간당 착수 승률 — 벤치 상대 대비 승률 측정
- 균형성 — 루트 자식 방문 분포 — 활용-탐색 상수별 방문 편중 확인

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 게임·바둑 AI: MCTS에 정책·가치 신경망(048·058 참조)을 결합(PUCT)해 시뮬레이션을 안내하고 초인간 수준 착수 결정
2. 실시간 의사결정: 로봇 경로·전략 시뮬레이션 게임에서 애니타임 특성으로 제한 시간 내 최선 행동 선택
3. 조합 최적화·스케줄링: 거대 탐색 공간의 순차 의사결정을 트리로 모델링하고 시뮬레이션 통계로 유망 해를 점진 탐색

**결론:**
- 기술사 판단: 상태공간이 거대하고 평가 함수 설계가 어려우면 MCTS(가능하면 신경망 안내)를, 분기수가 작고 좋은 평가 함수가 있으면 미니맥스+알파베타를, 단발 근사 추정이면 순수 몬테카를로(017)를 택하는 조건부 선택이 유효함
- 향후 방향: 자기대국 강화학습과 MCTS를 결합한 AlphaZero 계열이 게임을 넘어 신약·재료 탐색·계획 문제로 확장되며, 학습된 탐색 정책으로 시뮬레이션 효율을 높이는 방향으로 발전하고 있음
