# 📖 【암기용】 개념 완전 이해

> 목적: 촘스키 계층구조를 중심으로 형식 언어와 오토마타의 관계를 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 컴퓨터가 이해할 수 있는 언어(문자열 집합)의 문법적 생성 규칙을 수학적으로 정의하고 분류한 이론
- **왜 필요한가**: 프로그래밍 언어의 구문이 꼬이지 않는지(모호성), 무한루프 없이 텍스트를 읽어낼 수 있는지 수학적 한계를 증명하기 위해 필요하다.
- **핵심 직관**: 언어가 복잡할수록 인식하는 기계도 똑똑해져야 한다. 단순한 언어는 '상태'만 기억하는 기계(FSA)로 충분하지만, 복잡한 언어는 '메모리 스택'이나 '무한 테이프'가 필요하다(촘스키 4계층).

## 깊이 이해
- **배경·문제의식**: 기호의 집합(알파벳)과 치환 규칙만으로 자연어나 프로그래밍 언어를 정의하려 한 촘스키의 연구가 컴파일러 파싱 알고리즘의 기초가 되었다.
- **작동 원리 (촘스키 계층)**: 규칙($\alpha \rightarrow \beta$)의 제약 정도에 따라 4단계로 나눈다.
  - **Type 3 (정규 언어)**: 치환 후 변수가 무조건 하나만 맨 끝에 붙음 ($A \rightarrow aB$). 가장 제한적이라 메모리 없는 기계(FSA)가 정규표현식으로 인식 가능.
  - **Type 2 (문맥 자유 언어)**: 좌변이 단일 변수 1개 ($A \rightarrow \gamma$). 주변 문맥 안 보고 무조건 치환. 괄호를 기억하기 위한 스택 기계(PDA)가 인식. (프로그래밍 언어 구문)
  - **Type 1 (문맥 의존 언어)**: 양옆 기호(문맥)가 맞아야 치환 가능 ($\alpha A \beta \rightarrow \alpha \gamma \beta$). 선형 한계 오토마타(LBA)가 인식.
  - **Type 0 (귀납적 가산 언어)**: 무제약. 튜링 기계가 인식.
- **비유**: Type 3는 동전 넣으면 바로 반응하는 자판기, Type 2는 열린 괄호를 짝 맞출 때까지 임시 보관하는 스택 검사기, Type 0는 한계 없는 메인프레임 컴퓨터와 같다.
- **흔한 오해·주의점**: 프로그래밍 언어는 순수한 Type 2(문맥 자유)가 아니다. 변수를 선언해야만 쓸 수 있다는 규칙(의미 검사)은 문맥 의존(Type 1) 성격이 섞여 있다.

## 연결 개념
- 오토마타(Automata) — 각 계층의 형식 언어를 인식하고 수락/거절을 판별하는 수학적 상태 기계
- 정규 표현식 (Regular Expression) — 정규 언어(Type 3) 패턴을 표현, 컴파일러 어휘 분석(토크나이저)에 사용
- 파서 (Parser) — 문맥 자유 언어(Type 2) 규칙을 검증하며 구문 트리(AST)를 엮어내는 프로그램

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 촘스키 계층(Type 0~3)의 생성 규칙 제약과 대응하는 인식 오토마타 기계 모델의 1:1 수학적 포함 관계를 컴파일러 파이프라인과 연결하여 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 형식 언어 이론은 기호 집합으로 구성된 문자열이 생성 규칙(Grammar)을 통해 어떻게 파생되고 인식(Automata)되는지 수학적으로 제약하고 분류한 학문이다.
> 2. **가치**: 언어의 복잡도(촘스키 계층)와 처리 가능 기계를 1:1 매핑하여, 무한루프에 빠지지 않는 결정론적 컴파일러(어휘/구문 분석기) 설계의 수학적 근거를 제공한다.
> 3. **판단 포인트**: 언어 전체를 복잡한 Type 1 문법으로 설계하면 파싱 비용이 지수함수로 폭증하므로, 어휘(Type 3)와 뼈대(Type 2)로 쪼개어 계산 복잡도를 $O(N)$으로 통제해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 언어와 기계의 수학적 상관관계 이해 | 촘스키 4계층, 각 계층의 생성 규칙과 인식 오토마타 연결 | 단순히 기계 이름만 나열하고 생성 규칙($\alpha \rightarrow \beta$) 형태 차이 누락 |
| 실무 컴파일러 구성 파이프라인 맵핑 | Type 3(어휘 분석, 토큰)와 Type 2(구문 분석, AST) | 이론 설명에 그치고 컴파일러 단계 적용 설명 누락 |
| 벤 다이어그램식 포함 관계 명시 | Type 0 $\supset$ Type 1 $\supset$ Type 2 $\supset$ Type 3 억제 포함성 | 계층들이 상호 배타적 별개 집합인 것처럼 오해 서술 |

> 요약: 각 계층별 문법 규칙의 좌우변 제약 조건과 오토마타 구조를 정확히 짝짓고, 이것이 실제 컴파일러 최적화에 어떻게 쓰이는지 연결해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 알파벳 기호의 유한 집합에서 유도된 문자열들이 특정한 생성 규칙(Grammar)을 위반하지 않는지 수학적으로 제약하고 분류하는 체계
- 배경: 컴퓨터 언어 문법 정의 시 모호성을 배제하고, 이를 읽어내는 파서(Parser)가 종료 조건에 도달할 수 있는지 계산 복잡도 증명 필요
- 필요성: 프로그래밍 언어의 구문 분석 과정이 정지 문제(Halting Problem)에 직면하지 않도록, 파싱 가능성이 수학적으로 입증된 문맥 자유(Type 2) 이하 수준으로 뼈대 문법을 제약해야 함

## Ⅱ. 구조 및 구성요소 (문법의 4요소)

```text
형식 문법 G = (N, \Sigma, P, S)
S (시작 기호) -> P (규칙 \alpha \rightarrow \beta) 연쇄 적용 -> \Sigma (단말 기호) 조합 문자열 유도
```

| 구성요소 | 기호 | 의미 및 특이사항 |
|:---|:---:|:---|
| 비단말 기호 (Non-terminal) | $N$ | 유도 과정 중 다른 기호로 치환 가능한 임시 변수 기호 (예: `<Statement>`) |
| 단말 기호 (Terminal) | $\Sigma$ | 더 이상 치환되지 않고 최종 문장에 출력되는 언어 기본 알파벳 (예: `if`, `0`) |
| 생성 규칙 (Production Rule) | $P$ | 기호를 치환 확장하는 관계식 집합 (형태: 좌변 $\alpha \rightarrow$ 우변 $\beta$) |
| 시작 기호 (Start Symbol) | $S$ | 문법의 유도가 최초로 출발하는 특정 비단말 기호 ($S \in N$) |

> 요약: 형식 언어는 시작 기호 $S$에서 유한한 생성 규칙 $P$를 연속 반복 적용해 비단말 기호를 단말 기호 모음 $\Sigma$로 치환해 내는 논리적 추상 체계다.

## Ⅲ. 촘스키 계층 구조 및 흐름도

```text
계층 포함도: 귀납적 가산(Type 0) \supset 문맥 의존(Type 1) \supset 문맥 자유(Type 2) \supset 정규 언어(Type 3)
매핑 오토마타: (튜링 머신)        (선형 한계 오토마타)   (푸시다운 오토마타)       (유한 상태 기계)
```

| 계층 | 생성 규칙 제약 조건 ($\alpha \rightarrow \beta$) | 대응 기계 (인식 오토마타) | 실무 적용(컴파일러) |
|:---:|:---|:---|:---|
| **Type 3** (정규 언어) | $A \rightarrow aB$ 또는 $A \rightarrow a$ (우측 선형 제한, 엄격) | FSA (Finite State Automata) | 토크나이저(어휘 분석), 정규 표현식 검색 엔진 |
| **Type 2** (문맥 자유) | $A \rightarrow \gamma$ (좌변이 주변 상관없이 무조건 단일 비단말) | PDA (Pushdown Automata) | 구문 분석기(Parser, AST 트리 생성), 언어 기본 문법 |
| **Type 1** (문맥 의존) | $\alpha A \beta \rightarrow \alpha \gamma \beta$ (좌변 주변 조건과 일치 필요) | LBA (Linear Bounded Automata) | 의미 분석(선언부와 사용부의 변수 스코프 일치 검사) |
| **Type 0** (가산 언어) | 생성 규칙 좌우변 형태 제약 없음 | Turing Machine | 무한 계산 가능한 모든 컴퓨터 알고리즘 일반 |

> 요약: 생성 규칙의 좌우변 치환 제약이 엄격해질수록(Type 0 $\rightarrow$ 3) 언어의 문법 표현력은 줄어들지만, 처리 알고리즘 복잡도는 $O(N)$ 수준으로 대폭 감소한다.

## Ⅳ. 특징 및 컴파일러 계층 매핑 판단

| 컴파일 분석 | 적용 계층 | 주요 특징 및 처리 메커니즘 | 한계 및 트레이드오프 |
|:---|:---|:---|:---|
| 어휘 분석 (Lex) | Type 3 (정규) | 정규표현식을 $O(N)$ 상태 제어로 고속 스캔하여 토큰 분리 | 메모리 미지원으로 괄호 중첩 매칭 등 구조 분석 불가능 |
| 구문 분석 (Yacc) | Type 2 (문맥 자유)| LIFO 스택 메모리 운영으로 재귀적 괄호 짝 매칭 및 추상 트리(AST) 뼈대 구축 | 표현력 확장 시 비결정적 분기에 따른 파싱 시간 지연 발생 |
| 의미 분석 (Semantic)| Type 1 (문맥 의존)| 심볼 테이블(Symbol Table) 보조 자료구조를 추가하여 변수 선언/타입 무결성 검증 | 오토마타 전수 파싱 시 복잡도 폭증이므로 Type 2 + 별도 테이블로 회피 |

> 요약: 현대 실용 컴파일러 파이프라인은 복잡한 Type 1 문법을 통째로 파싱하지 않고, Type 2 파서로 골격을 잡은 뒤 해시 테이블로 문맥(Type 1 속성)을 사후 통제한다.

## Ⅴ. 심화 비교 (Type 2 vs Type 3) 및 리스크

| 비교 축 | Type 3 (정규 언어) | Type 2 (문맥 자유 언어) | 선택 기준 |
|:---|:---|:---|:---|
| 메모리 구조 | 현재 상태(State) 레지스터만 존재, 무기억 | 무한 깊이 보관 가능한 스택(Stack) 메모리 보유 | 괄호 매칭 등 깊이 중첩 보관 필요성 여부 |
| 규칙 형태 | $A \rightarrow aB$ (비단말은 끝에 1개만 허용) | $A \rightarrow \gamma$ (좌변 비단말 1개가 마음대로 치환됨) | 문법 확장의 계층적 재귀성(Recursion) 요구도 |
| 도구 구현 | Lex, Flex, 각종 정규표현식 라이브러리 엔진 | Yacc, Bison (LALR 등 파서 제너레이터) | 선형 패턴 매칭(단어 단위)인지 트리 구조 조립(문장)인지 판별 |

> 요약: 입력 문자열을 $O(N)$ 정규 언어 기계로 잘게 토큰화한 뒤, 이를 스택 오토마타로 넘겨 구조화하는 이원화 패턴이 성능 확보의 정석이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 구문 모호성 (Ambiguity) | 문맥 자유(Type 2) 문법 특성상 동일 수식에 2개 이상 구문 트리 생성 시점 발생 | 연산자 우선순위 강제 부여 및 좌측 인수분해(Left Factoring) 문법 재작성 | 파서 Shift/Reduce 모호성 경고 0건 |
| 정규표현식 백트래킹 공격 | 비결정적(NFA) 상태 전이 시 중첩 반복자(Catastrophic Backtracking)로 $O(2^N)$ 폭주 | 비결정적 분기를 컴파일 타임에 결정론적 오토마타(DFA) 엔진으로 변환 강제 | 페이로드 문자열 처리 지연 SLA 초과 건수 |

> 요약: Type 2 문법의 모호성은 테이블 규칙 재작성으로 회피하고, Type 3 정규식 처리 지연은 DFA 구조 도입으로 $O(N)$ 고속 탐색을 락인해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. DSL(도메인 특화 언어) 생성기 구현: 사내 배포 파이프라인 설정 파일 문법 규칙을 구축할 때, ANTLR 도구를 통해 문맥 자유 문법(Type 2, BNF)으로 정의하고 $O(N)$ 속도의 파서를 자동 생성하여 문법 모호성 원천 차단
2. 정규표현식(WAF) 한계 대응 룰셋 고도화: 웹 방화벽 환경에서 SQL Injection의 괄호 깊이 중첩 탐지 등 Type 3 정규식 엔진 우회 공격을 막기 위해, Type 2 괄호 매칭 파서 로직을 WAF 엔진 탐지 코어에 부분 이식
3. 취약점 정적 분석(SAST) 적용 체계: 단순히 소스코드 라인을 그렙(grep)하는 토큰 탐색(Type 3)에서 벗어나, 상용 컴파일러 Front-end 연계 구문 트리(AST) 횡단 및 심볼 흐름 추적(Type 2+1 복합)으로 보안 취약 탐지율 95% 이상 확보

**결론 (2줄):**
- 기술사 판단: 형식 언어 계층은 이론을 넘어, 입력 파싱 모듈 설계 시 성능 붕괴(무한루프)를 피하고자 문법 규칙을 결정론적 $O(N)$ 연산 기계(Type 3/2)로 하향 매핑하는 핵심 아키텍처 기준선이다.
- 향후 방향: 최근 대규모 언어 모델(LLM)이 프로그래밍 코드 생성을 돕고 있으나, 생성 결과물이 시스템 오류를 내지 않는지 수학적으로 증명(Verification)하는 엔진 코어 영역은 여전히 오토마타 기반 파서가 담당한다.
