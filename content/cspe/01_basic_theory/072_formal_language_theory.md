# 📖 【암기용】 개념 완전 이해

> 목적: 형식 언어 이론을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 문자열 집합을 문법과 자동자 모델로 엄밀하게 표현하는 계산 이론
- **왜 필요한가**: 프로그래밍 언어, 정규식, 컴파일러, 프로토콜 명세는 "어떤 문자열이 허용되는가"를 판정해야 한다. 형식 언어는 허용 규칙을 수학적으로 기술한다.
- **핵심 직관**: 문법은 문자열을 만드는 규칙이고, 자동자는 문자열을 읽으며 규칙 위반 여부를 판정하는 기계다.

## 깊이 이해
- **배경·문제의식**: 자연어는 의미와 예외가 많지만 컴퓨터 언어는 기계가 판정 가능해야 한다. Chomsky 계층은 문법의 표현력과 이를 인식하는 자동자의 계산 능력을 4단계로 정리한다.
- **작동 원리**: 정규 언어는 유한 상태 자동자와 정규식으로 표현되고, 문맥자유 언어는 pushdown automaton과 CFG로 표현된다. 문맥민감 언어와 재귀 열거 언어는 더 큰 메모리와 튜링 기계 모델을 필요로 한다.
- **비유**: 입장 규칙이 단순한 행사장은 표 색상만 보면 되고, 중첩 괄호를 확인하는 행사는 스택에 입장 기록을 쌓아야 하는 것과 같다.
- **구체 예시**: `a*b*`는 정규식과 DFA로 판정 가능하지만, `{a^n b^n | n>=1}`은 개수를 맞춰야 하므로 스택을 쓰는 CFG/PDA가 필요하다.
- **흔한 오해·주의점**: 정규식 엔진이 모든 문법을 처리한다는 생각은 틀렸다. 중첩 괄호, 블록 구조, 함수 호출 인자는 CFG 수준 파서가 필요하다.

## 연결 개념
- 정규식·DFA — 어휘 분석과 패턴 매칭의 기초
- CFG·PDA — 프로그래밍 언어 구문 분석의 기반
- 튜링 기계 — 계산 가능성과 결정 가능성 논의의 기준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 형식 언어 이론은 문자열 집합을 생성 문법과 인식 자동자로 분류하는 계산 이론임.
> 2. **가치**: 정규식, 컴파일러 파서, 프로토콜 문법, 입력 검증에서 허용 문자열을 기계적으로 판정함.
> 3. **판단 포인트**: Chomsky 계층은 표현력 증가와 판정 비용 증가를 함께 보며, 문제에 맞는 최소 문법을 선택해야 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 문자열 집합의 생성·인식 규칙을 수학적으로 표현하는 계산 이론
- 배경: 소스코드, JSON, SQL, 네트워크 메시지는 허용 문법을 벗어나면 처리 결과가 달라짐
- 필요성: 문법 계층, 자동자, 파싱 가능성을 기준으로 입력 검증과 컴파일러 설계를 수행해야 함

---

## Ⅱ. 구조 및 구성요소

```text
알파벳 -> 문자열 -> 언어 -> 문법 -> 자동자 -> 판정 결과
          +-> 생성 규칙
          +-> 인식 기계
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 알파벳 | 기호의 유한 집합 | 예: {a,b}, ASCII, token set |
| 언어 | 알파벳으로 만든 문자열 집합 | 유한/무한 집합 모두 가능 |
| 문법 | 문자열 생성 규칙 | 정규, 문맥자유, 문맥민감 |
| 자동자 | 문자열 인식 기계 | DFA, PDA, LBA, Turing Machine |

> 요약: 형식 언어는 기호 집합에서 문자열을 만들고, 문법과 자동자로 생성·인식 가능성을 판정함.

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 규칙 식별 -> 언어 계층 선택 -> 문법 작성 -> 자동자 구성 -> 문자열 판정
                  +-> 정규/문맥자유/문맥민감
                  +-> 결정 가능성 확인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 허용 문자열 패턴 식별 | 예시/반례 5개 이상 작성 |
| 2 | Chomsky 계층 매핑 | Type-3, Type-2, Type-1, Type-0 |
| 3 | 문법 또는 자동자 구성 | production rule, state transition |
| 4 | membership 판정 | acceptance, rejection, parsing error |

> 요약: 문자열 규칙을 계층에 배치한 뒤 해당 문법과 자동자로 수용 여부를 검증함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 정규 언어 | 유한 상태로 판정 | DFA/NFA, lexer, O(n) 스캔 |
| 문맥자유 언어 | 스택으로 중첩 구조 판정 | CFG, PDA, LL/LR parser |
| 문맥민감 언어 | 입력 길이에 비례한 제한 메모리 | LBA, 복잡한 의존 규칙 |
| 재귀 열거 언어 | 튜링 기계로 인식 | 정지 문제와 결정 불가능성 |

> 요약: 계층이 올라갈수록 표현력은 커지지만 구현 비용과 판정 난도가 함께 증가함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 입력 검증 | ad-hoc if문 | 정규식/DFA | 단순 패턴은 Type-3 |
| 언어 구문 | 정규식 | CFG/Parser | 중첩 괄호·블록은 Type-2 |
| 계산 한계 | 경험적 판정 | 튜링 기계·결정 가능성 | 무한 탐색 문제는 정지성 검토 |

> 요약: 문자열 구조가 단순하면 정규 언어, 중첩 구조가 있으면 문맥자유 언어를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과도한 표현력 | CFG가 필요한 문제에 Type-0 도구 사용 | 최소 계층 원칙 적용 | 파서 복잡도 O(n) 또는 O(n^3) 확인 |
| ReDoS | 백트래킹 정규식 폭발 | DFA 기반 엔진, timeout 설정 | 입력 1KB당 처리시간 |
| 문법 모호성 | 하나의 문자열에 parse tree 다수 | precedence, associativity 명시 | shift/reduce conflict 0건 |

> 요약: 표현력 과다, 정규식 폭발, 문법 모호성은 최소 계층과 파서 검증으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 판정 정확도 | 양성/음성 테스트 100% 통과 | grammar test suite |
| 처리 비용 | O(n) lexer, 파서 충돌 0건 | benchmark, parser generator report |
| 운영 보안 | ReDoS timeout 100ms 이하 | fuzzing, 악성 입력 테스트 |

> 요약: 형식 언어 적용 결과는 테스트 통과율, 시간복잡도, 악성 입력 내성으로 검증함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 입력 검증: 단순 ID, 이메일, 토큰은 DFA 기반 정규식으로 제한하고 timeout 100ms 설정
2. DSL/프로그래밍 언어: CFG로 문법 작성, LL/LR 파서 생성기에서 conflict 0건 확인
3. 보안 검증: fuzzing 10,000건 이상, ReDoS payload, 모호 문법 테스트를 CI에 포함

**결론 (2줄):**
- 기술사 판단: 단순 패턴은 정규 언어, 중첩 구조는 문맥자유 언어, 계산 한계 논의는 튜링 기계 기준으로 판정
- 향후 방향: API 스키마, IaC, DSL 검증은 형식 문법과 자동 테스트 결합이 필수 조건임
