## 미리 알고가기

- 컴파일러: 고급 언어 소스 코드를 목적 코드나 실행 코드로 변환하는 번역 시스템임
- 프론트엔드: 소스 언어를 분석해 토큰, AST, 의미 정보, IR을 만드는 영역임
- 백엔드: IR을 최적화하고 타겟 기계어 또는 목적 코드로 바꾸는 영역임
- IR: 소스 언어와 타겟 기계어 사이의 중간 표현이며 최적화와 이식성의 기준임
- 심볼 테이블: 식별자, 타입, 스코프, 메모리 위치 같은 의미 정보를 저장하는 표임
- 최적화 패스: IR이나 기계어를 더 빠르거나 작게 만들기 위해 반복 적용하는 변환 단계임

## Ⅰ. 개요

- **정의**: 컴파일러 구조는 고급 언어 소스 코드를 어휘·구문·의미 분석으로 이해하고, IR 최적화와 코드 생성을 거쳐 타겟 환경에서 실행 가능한 코드로 변환하는 단계적 아키텍처임. 소스 언어와 하드웨어 타겟을 분리해 이식성, 성능, 오류 검출을 확보하기 위해 사용함
- **배경/필요성**: 하나의 언어를 여러 CPU와 운영체제에서 실행하려면 언어 분석과 기계어 생성 책임을 분리한 구조가 필요함
- **비유**: 원문을 단어로 나누고 문장 구조를 파악한 뒤 중간 번역문을 다듬어 최종 언어로 옮기는 전문 번역 공정과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 단계별 구조 설명 | Lexer, Parser, Semantic, IR, Optimizer, CodeGen | 인터프리터와 단순 혼동 |
| 프론트엔드·백엔드 분리 이유 | IR 기반 모듈화와 다중 타겟 지원 | 최적화 위치 누락 |

> 요약: 컴파일러는 소스 언어 분석과 타겟 코드 생성을 IR로 분리해 오류 검출, 최적화, 이식성을 달성하는 변환 파이프라인임

## Ⅱ. 특징/비교

| 판단 기준 | 인터프리터 | 단순 컴파일러 | 현대 컴파일러 |
|:---|:---|:---|:---|
| 실행 방식 | 소스를 실행 시점에 해석함 | 소스를 목적 코드로 직접 변환함 | IR 기반 다단계 분석·최적화를 수행함 |
| 성능 특성 | 시작은 빠르지만 반복 실행 비용이 큼 | 실행 성능은 좋지만 최적화가 제한적임 | 정적·프로파일 기반 최적화가 가능함 |
| 이식성 | 런타임이 플랫폼 차이를 흡수함 | 타겟별 구현 부담이 큼 | 프론트엔드와 백엔드를 조합 가능함 |
| 선택 기준 | 스크립트·동적 실행 | 단순 언어·제한된 타겟 | 범용 언어·다중 타겟·고성능 |

> 요약: 현대 컴파일러는 IR을 중심으로 언어 분석과 하드웨어 생성을 분리해 성능과 이식성을 동시에 확보함

- **프론트엔드 기준**: 소스 언어의 문법과 타입 규칙을 정확히 검사하는 역할이 핵심임
- **미들엔드 기준**: IR 최적화는 언어와 타겟에 독립적인 성능 개선을 담당함
- **백엔드 기준**: 타겟 ISA, 레지스터, 호출 규약을 반영해 실제 실행 코드를 생성함

## Ⅲ. 구성요소

```text
+---------+    +---------+    +---------+    +---------+    +---------+
| Lexer   | -> | Parser  | -> | Semantic| -> | IR Opt  | -> | CodeGen |
| tokens  |    | AST     |    | checks  |    | passes  |    | object  |
+----+----+    +----+----+    +----+----+    +----+----+    +----+----+
     |              |              |              |              |
     v              v              v              v              v
 source text    syntax tree   symbol table   optimized IR    target code
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 어휘 분석기 | 문자 스트림을 키워드, 식별자, 리터럴 같은 토큰으로 분리함 | 단어 분리기 |
| 구문 분석기 | 토큰 열을 문법 규칙에 맞춰 AST로 구조화함 | 문장 해석기 |
| 의미 분석기 | 타입, 스코프, 선언 여부를 검사하고 심볼 테이블을 관리함 | 교정 편집자 |
| IR 최적화기 | 상수 접기, 데드 코드 제거, 루프 최적화 등 변환을 수행함 | 초안 다듬기 |
| 코드 생성기 | 명령어 선택, 레지스터 할당, 목적 코드 출력을 수행함 | 최종 인쇄기 |

> 요약: 컴파일러는 토큰화부터 코드 생성까지 각 단계의 산출물을 다음 단계 입력으로 넘기는 구조적 변환 시스템임

## Ⅳ. 절차

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Analyze   | --> | Build IR  | --> | Optimize  | --> | Emit      |
| Source    |     | AST / SSA |     | Passes    |     | Machine   |
+-----------+     +-----------+     +-----------+     +-----------+
      |                 |                 |                 |
      v                 v                 v                 v
errors early       portable form      faster/smaller     object file
```

1. **소스 분석**: 어휘·구문·의미 분석을 수행해 오류를 조기에 찾고 AST와 심볼 정보를 생성함
2. **중간 표현 생성**: AST를 SSA나 3주소 코드 같은 IR로 변환해 언어와 타겟 의존성을 낮춤
3. **최적화 수행**: IR과 타겟 정보를 기준으로 성능, 코드 크기, 전력 사용량을 개선하는 패스를 적용함
4. **목적 코드 생성**: 타겟 ISA에 맞게 명령어를 선택하고 레지스터를 할당한 뒤 목적 파일을 출력함

> 요약: 컴파일 절차는 소스 분석, IR 생성, 최적화, 타겟 코드 생성으로 이어지는 단계별 품질 보증 흐름임

## Ⅴ. 문제점

- **P1 다중 타겟 유지보수 부담**: CPU, GPU, NPU, RISC-V처럼 타겟이 늘어나면 백엔드 구현과 검증 비용이 증가함
- **P2 빌드 시간 증가**: 최적화 패스와 정적 분석이 많아질수록 대규모 프로젝트의 빌드 시간이 길어짐
- **P3 정적 최적화 한계**: 컴파일 시점에는 실제 실행 입력과 핫 경로 정보를 모두 알 수 없어 최적화가 제한됨

> 요약: 현대 컴파일러의 운영 문제는 타겟 다양성, 최적화 비용, 실행 시점 정보 부족에서 발생함

## Ⅵ. 개선방안

- **P1 대응**: LLVM IR, MLIR 같은 공통 IR을 활용해 프론트엔드와 백엔드를 조합 가능한 구조로 설계함 (확인: 신규 타겟 지원 기간)
- **P2 대응**: 증분 컴파일, 캐시, 분산 빌드, 최적화 레벨 분리로 빌드 시간을 통제함 (확인: clean/incremental build 시간)
- **P3 대응**: PGO, JIT, AOT+runtime profile 결합으로 실행 정보를 최적화에 반영함 (확인: benchmark 성능 개선율)

> 요약: 공통 IR, 빌드 최적화, 프로파일 기반 최적화를 적용해야 컴파일러의 이식성과 성능을 동시에 확보할 수 있음

## Ⅶ. 전망

- **향후 발전 방향**: AI 가속기와 이기종 컴퓨팅 확대로 MLIR, XLA, TVM 같은 도메인 특화 컴파일러의 중요성이 커질 전망임
- **기술사적 판단**: 신규 하드웨어 도입 시 연산 성능뿐 아니라 컴파일러 백엔드와 도구 체인의 성숙도를 함께 평가해야 함
- **기술사 제언**: 답안에서는 컴파일러를 단순 번역기가 아니라 IR 중심의 구조설계와 최적화 체계로 설명해야 함
- **답안 포인트**: 프론트엔드, 미들엔드, 백엔드의 산출물 연결 관계를 쓰면 단계별 책임이 명확해짐
- **운영 포인트**: 빌드 시간과 실행 성능은 서로 trade-off가 있으므로 최적화 레벨을 환경별로 달리함
- **선택 포인트**: 다중 타겟 지원은 언어 기능보다 IR과 백엔드 생태계 성숙도가 좌우함
