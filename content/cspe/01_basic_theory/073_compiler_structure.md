# 073. 컴파일러 구조 — 어휘·구문·의미 분석 (Compiler Structure)

## Ⅰ. 개요

- **정의/개념**: 특정 프로그래밍 언어로 작성된 소스 코드를 다른 언어(주로 저수준의 기계어)로 번역하기 위해 어휘 분석, 구문 분석, 의미 분석, 최적화, 코드 생성의 단계를 거치는 소프트웨어 시스템임
- **배경/필요성**: 인간이 이해하기 쉬운 고수준 언어의 추상화된 논리를 하드웨어가 실행 가능한 물리적 명령어로 변환하고, 실행 효율성을 높이기 위한 최적화 과정을 자동화하기 위해 필수적임

## Ⅱ. 특징 및 비교 (프론트엔드 vs 백엔드)

| 판단 기준 | 프론트엔드 (Front-end) | 미들엔드 (Middle-end) | 백엔드 (Back-end) |
|:---|:---|:---|:---|
| **주요 역할** | 소스 코드 분석 및 검증 | 플랫폼 독립적 최적화 | 타겟 시스템 코드 생성 |
| **핵심 단계** | 어휘/구문/의미 분석 | IR(중간 표현) 최적화 | 코드 생성, 레지스터 할당 |
| **의존성** | 소스 언어에 종속적 | 독립적 (범용) | 타겟 아키텍처에 종속적 |
| **산출물** | AST (추상 구문 트리) | 최적화된 IR | 목적 코드 (Object Code) |

> 요약: 프론트엔드는 소스의 '의도'를 파악하고, 백엔드는 타겟 장치에 '최적화'된 명령을 내림

## Ⅲ. 구성요소/구조

- **구성요소**:
  - **Lexical Analyzer (Scanner)**: 소스 코드를 의미 있는 최소 단위인 토큰(Token)으로 분리함 (정규 문법 활용)
  - **Syntax Analyzer (Parser)**: 토큰의 배열이 문법 규칙에 맞는지 확인하고 파스 트리(Parse Tree)를 생성함 (문맥 자유 문법 활용)
  - **Semantic Analyzer**: 변수 선언 여부, 타입 일치성 등 논리적 오류를 검증하고 심볼 테이블(Symbol Table)을 갱신함
  - **Intermediate Code Generator**: 소스 언어와 기계어의 중간 형태인 IR을 생성하여 최적화의 기반을 마련함
  - **Code Optimizer**: 실행 시간 단축 및 메모리 절약을 위해 불필요한 코드를 제거하거나 루프를 최적화함

- **컴파일 단계 흐름도**:
```text
[소스 코드] -> [어휘 분석] -> [구문 분석] -> [의미 분석] -> [중간 코드 생성] -> [최적화] -> [코드 생성] -> [목적 코드]
                  |            |            |               |               |            |
                (토큰)      (AST)      (Annotated)        (IR)           (Opt-IR)      (ASM)
```

## Ⅳ. 문제점 및 개선방안

1. **[모호한 문법 정의]**: 구문 분석 단계에서 하나의 코드에 대해 여러 파스 트리가 생성되어 해석의 혼선이 발생함
   - **개선방안**: 연산자 우선순위와 결합 법칙을 명시한 비모호한 문법(Unambiguous Grammar)으로 재정의함 (확인: 파스 트리 유일성)
2. **[최적화와 디버깅의 트레이드오프]**: 과도한 코드 최적화는 실행 순서를 변경하여 디버깅 시 원본 코드와의 대응을 어렵게 함
   - **개선방안**: 디버깅 정보를 포함하는 심볼 테이블을 유지하고, 개발 단계에 따라 최적화 레벨(O0~O3)을 조정함 (확인: 심볼 매핑 정확도)
3. **[타겟 아키텍처 확장성 부족]**: 백엔드가 특정 CPU에 강하게 결합되면 새로운 하드웨어 지원에 많은 비용이 소요됨
   - **개선방안**: LLVM과 같은 공통 중간 표현(IR) 기반의 모듈형 컴파일러 구조를 채택하여 백엔드만 교체 가능하게 함 (확인: 아키텍처 이식성)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **정적 분석 도구** | 컴파일러 프론트엔드(AST)를 활용하여 코드 내 보안 취약점 및 안티 패턴 탐지 | 탐지 정밀도, 오탐률 |
| **크로스 컴파일** | 하나의 소스 코드를 다양한 타겟(iOS, Android, 임베디드)용 백엔드로 각각 빌드 | 빌드 성공률, 타겟별 성능 |
| **JIT 컴파일러** | 실행 시점에 빈번히 호출되는 핫스팟(Hotspot) 코드를 기계어로 즉시 번역 및 최적화 | 런타임 성능, 메모리 오버헤드 |

> 요약: 실무에서는 LLVM이나 GCC와 같은 오픈소스 프레임워크를 활용하여 새로운 언어나 타겟 아키텍처를 빠르게 지원함

## Ⅵ. 결론

컴파일러 구조는 단순히 언어를 번역하는 단계를 넘어, 프로그램의 논리적 무결성을 검증하고 하드웨어 자원을 극대화하는 복합적인 최적화 시스템으로 진화했음. 특히 클라우드와 임베디드 환경이 공존하는 현대 컴퓨팅 환경에서, 소스 언어의 독립성을 보장하는 프론트엔드와 다양한 타겟에 대응하는 백엔드의 분리 구조는 소프트웨어 생태계의 확장성을 지탱하는 핵심적인 아키텍처로 자리 잡고 있음.
