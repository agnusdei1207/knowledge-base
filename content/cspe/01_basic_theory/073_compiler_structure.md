# 컴파일러 구조 - 프론트엔드·백엔드 (Compiler Structure)

## 1. 개요

- **정의/개념**: 컴파일러는 고급 언어로 작성된 소스 코드를 분석·변환·최적화해 목적 코드나 실행 가능한 형태로 바꾸는 소프트웨어이다.
- **배경/필요성**: 프로그래밍 언어의 추상 표현을 하드웨어가 실행 가능한 명령으로 바꾸려면 문법 분석, 의미 검증, 최적화, 코드 생성이 단계적으로 필요하다.

컴파일러의 핵심은 단순 번역이 아니라 소스 의미를 보존하면서 중간 표현을 거쳐 실행 효율을 높이는 구조이다.

## 2. 특징 및 비교

| 구분 | 프론트엔드 | 미들엔드 | 백엔드 |
|---|---|---|---|
| 역할 | 소스 분석 | IR 최적화 | 목적 코드 생성 |
| 주요 단계 | 어휘·구문·의미 분석 | 최적화 | 레지스터 할당, 코드 생성 |
| 입력 | 소스 코드 | IR | 최적화된 IR |
| 출력 | AST, Symbol Table | 최적 IR | 기계어·바이트코드 |

선택 기준은 언어 독립성, 타깃 아키텍처, 최적화 수준, 빌드 시간, 디버깅 가능성이다.

## 3. 구성요소/구조

| 구성요소 | 설명 | 핵심 포인트 |
|---|---|---|
| Lexer | 문자 스트림을 토큰으로 변환 | 정규 언어 |
| Parser | 토큰을 AST로 변환 | CFG |
| Semantic Analyzer | 타입·스코프 검증 | 의미 오류 |
| IR | 중간 표현 | 최적화 기준 |
| Code Generator | 타깃 코드 생성 | 아키텍처 의존 |

```text
Source -> Lexer -> Parser -> Semantic -> IR -> Optimization -> CodeGen
```

앞 단계 오류가 뒤 단계로 전파되므로 컴파일러는 단계별 산출물과 검증 기준이 명확해야 한다.

## 4. 문제점 및 개선방안

1. **오류 메시지 품질**
   - 분석 단계가 불명확하면 사용자가 원인을 찾기 어렵다.
   - **개선방안**: 위치 정보, 복구 가능한 parser, 단계별 진단 메시지를 제공한다.

2. **최적화와 디버깅 충돌**
   - 최적화가 강하면 원본 코드와 실행 코드 대응이 어려워진다.
   - **개선방안**: debug info 유지, 최적화 레벨 선택, symbol mapping을 제공한다.

3. **타깃 의존성 증가**
   - 백엔드가 특정 아키텍처에 강하게 묶이면 확장성이 떨어진다.
   - **개선방안**: IR 중심 구조와 target-specific backend를 분리한다.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|---|---|---|
| 언어 구현 | Lexer/Parser/IR/CodeGen 파이프라인 구성 | 컴파일 성공률 |
| 성능 최적화 | IR 최적화로 실행 코드 효율 개선 | 실행 시간, 코드 크기 |
| 정적 분석 | AST와 symbol table로 오류·취약점 탐지 | 탐지율, 오탐률 |

## 6. 결론

컴파일러는 소스 코드를 단계적으로 분석하고 IR을 중심으로 최적화해 실행 가능한 코드로 바꾸는 구조이다. 어휘·구문·의미 분석에서 백엔드 코드 생성까지 흐름이 이어져야 컴파일러를 단순 번역기가 아니라 구조화된 변환 시스템으로 설명할 수 있다.
