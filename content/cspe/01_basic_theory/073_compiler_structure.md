## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 고급 프로그래밍 언어로 작성된 소스 코드를 컴퓨터가 이해할 수 있는 기계어로 변환하는 번역 프로그램의 전체 아키텍처임. |
| 배경/필요성 | 하드웨어 독립적으로 개발된 코드를 효율적으로 실행 가능한 타겟 목적 코드로 자동 변환하기 위해 필요. |
| 출제 의도 | 프론트엔드와 백엔드의 분리 구조 및 단계별 코드 분석/최적화 기법에 대한 이해도 평가. |

## Ⅱ. 구성요소
```text
+-----------+    +-----------+    +-----------+
| Lex Anlyz | -> | Syn Anlyz | -> | Code Gen  |
+-----------+    +-----------+    +-----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 어휘 분석기(Lexer) | 소스 코드를 읽어 의미 있는 최소 단위인 토큰으로 분할 | 단어 쪼개기 |
| 구문 분석기(Parser)| 토큰 열이 문법에 맞는지 검사하고 추상 구문 트리(AST) 생성 | 문장 구조화 |
| 코드 생성기 | 최적화된 중간 코드를 바탕으로 타겟 기계어/어셈블리어 생성 | 번역기 |

> 요약: 소스 코드를 토큰화하고 트리로 구조화한 뒤 최적화를 거쳐 실행 가능한 기계어로 변환함.

## Ⅲ. 절차
```text
+----------+   +----------+   +----------+   +----------+
| Tokenize |-> | AST Gen  |-> | InterCode|-> | Obj Code |
+----------+   +----------+   +----------+   +----------+
```
1. 어휘 분석: 정규 표현식을 이용해 소스 코드 문자를 토큰으로 분리함.
2. 구문/의미 분석: 파서를 통해 AST를 만들고 타입 체킹 등 의미적 무결성 확인함.
3. 중간 코드 및 최적화: 플랫폼 독립적인 중간 코드를 생성하고 루프/메모리 최적화 수행함.
4. 목적 코드 생성: 타겟 아키텍처에 맞는 최종 기계어를 도출함.

> 요약: 전단부에서 코드를 분석하여 트리 형태로 만들고 후단부에서 중간 코드를 최적화하여 기계어를 생성함.

## Ⅳ. 문제점
- 다양한 CPU 타겟(ARM, x86 등)마다 컴파일러 백엔드를 새로 개발해야 하는 중복 비용 발생
- 복잡한 코드 최적화 패스(Pass)가 늘어날수록 프로그램의 전체 빌드 시간이 과도하게 지연됨
- 분산/병렬 컴퓨팅 환경에 특화된 코드 최적화를 정적 컴파일 단계에서 완벽히 수행하기 한계

## Ⅴ. 개선방안
- [단기] LLVM 아키텍처 등 프론트엔드와 백엔드가 분리된 모듈형 프레임워크 적극 수용
- [중기] JIT(Just-In-Time) 컴파일과 AOT 컴파일의 장점을 융합한 하이브리드 빌드 최적화 적용
- [장기] AI 기반 동적 프로파일링 및 슈퍼컴파일링 알고리즘 연구로 자동화 최적화 구현

## Ⅵ. 전망
- 다양한 이기종 가속기(NPU, GPU)를 지원하기 위한 AI 특화 컴파일러(TVM 등)로 아키텍처가 빠르게 확장 중임.
