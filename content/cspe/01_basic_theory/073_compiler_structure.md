# 📖 【암기용】 개념 완전 이해

> 목적: 소스코드가 기계어로 번역되는 컴파일러 파이프라인 전체를 직관적으로 꿰뚫게 만든다.

## 한눈에
- **개요**: 인간이 작성한 고급 언어(C, Java)를 컴퓨터 CPU가 실행할 수 있는 저급 언어(어셈블리, 기계어)로 번역하는 단계적 파이프라인
- **왜 필요한가**: 복잡한 문장을 기계어로 한 번에 1:1 번역할 수 없다. 단어를 쪼개고(어휘), 뼈대를 세우고(구문), 뜻을 맞추어(의미) 다듬어야 멀티 플랫폼 지원과 최적화가 가능하다.
- **핵심 직관**: 전반부(Front-end)는 소스코드를 읽고 분석해 CPU 종류와 무관한 공용 중간 코드(IR)를 뽑아내고, 후반부(Back-end)는 이 중간 코드를 가져다 특정 인텔/ARM 칩셋에 맞춰 최적화된 기계어를 찍어낸다.

## 깊이 이해
- **전반부 (Front-end) — 분석**: 
  - **어휘 분석(Lexical)**: 문자열 `int a = 5;`를 `[INT]`, `[ID:a]`, `[=]`, `[NUM:5]` 등 의미 있는 덩어리(토큰)로 쪼갠다.
  - **구문 분석(Syntax)**: 토큰 조각들을 조합해 괄호 짝이나 주어-동사 문법이 맞는지 추상 구문 트리(AST) 뼈대를 짠다. (세미콜론 누락 에러 감지)
  - **의미 분석(Semantic)**: 문법 뼈대는 맞아도 말이 안 되는 연산(문자열 + 정수)을 심볼 테이블(변수 타입 정보)을 뒤져서 걸러낸다.
- **중간 단계**: 분석이 끝난 순수 논리를 중간 표현(IR) 코드 구조로 뱉어낸다. 이 덕분에 C++ 프론트엔드 하나로 여러 종류의 하드웨어 백엔드와 조립할 수 있다 (LLVM 아키텍처).
- **후반부 (Back-end) — 합성**:
  - **코드 최적화(Optimization)**: 계산 중복 제거, 루프 펼치기 등 실행 속도가 빨라지도록 IR 코드를 논리적으로 다듬는다.
  - **코드 생성(Code Generation)**: 다듬어진 IR을 타겟 칩셋 명령어 구조에 맞춰 번역하고 레지스터를 할당해 최종 기계어를 완성한다.
- **비유**: 번역 회사가 한국어 원고(소스)를 형태소 단위로 자르고(어휘) → 문장 구조 파악(구문) → 문맥 오역 수정(의미)을 거쳐 '표준 공용어(IR)'로 만든 뒤, 독일어/불어 전문가(백엔드)들이 각국 현지화 출판(생성)을 하는 분업화 공장과 같다.

## 연결 개념
- 파서 (Parser) — 구문 분석 단계에서 문맥 자유 문법 규칙을 확인하고 AST를 생성하는 구문 분석 핵심 모듈
- 촘스키 계층 (Chomsky Hierarchy) — 어휘(정규언어), 구문(문맥자유언어) 분석기의 수학적 복잡도 한계를 증명한 이론 기초
- LLVM 프레임워크 — 중간언어(IR)를 중심으로 프론트와 백엔드를 완벽히 디커플링하여 컴파일러 모듈화를 이룩한 현대적 아키텍처

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 6단계 파이프라인(어휘-구문-의미-중간-최적화-생성)의 입력/산출물 흐름을 보이고, IR 기반 전/후반부 디커플링이 주는 이식성과 최적화 비용 절감 효과를 부각한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 컴파일러는 고수준 언어 코드를 기계어로 번역하기 위해, 언어를 종속 분석하는 전반부(Front-end)와 하드웨어 종속 코드를 합성하는 후반부(Back-end)로 나뉜 시스템이다.
> 2. **가치**: 컴파일 단계를 분할해 어휘/구문 오류를 순차 필터링하고, 공통된 중간 표현(IR)을 통해 기계 독립적 최적화(루프 제거 등)를 별도 수행할 수 있다.
> 3. **판단 포인트**: N개 언어와 M개 CPU 아키텍처 대응 시 $N \times M$ 중복 개발 공수를 억제하기 위해, LLVM 체계처럼 IR을 기준으로 프론트($N$)와 백엔드($M$)를 분리해 확장성을 통제해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라인 단계별 변환 흐름 파악 | Token $\rightarrow$ AST $\rightarrow$ IR $\rightarrow$ 기계어 순차 산출물 변화 | 6단계 이름만 외워 적고 각 단계 결과물과 에러 감지 포인트 누락 |
| 자료구조와 컴파일러 통제 기제 파악 | 심볼 테이블 (Symbol Table) 운용, 에러 핸들러 통제 | 구문 분석과 의미 분석 시 심볼 테이블 참조 역할 누락 |
| 현대 컴파일러 모듈형 아키텍처 특성 | Front-end / Back-end 분리 구조, 중간 언어(IR) 역할 | 런타임에 해석하는 인터프리터 방식 동작과 혼용 서술 |

> 요약: 컴파일러 6단계의 순차적 데이터 변환 흐름을 명시하고, 심볼 테이블을 통한 문맥 정보 공유와 IR 기반 아키텍처 이식성 확보 방안을 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 인간 친화적인 고급 프로그래밍 언어 소스코드를 분석하여 컴퓨터 아키텍처 종속적인 저수준 목적 코드(기계어)로 번역하는 시스템 프로그램
- 배경: CPU 아키텍처(x86, ARM)마다 고유한 기계어 명령어 구조가 달라 프로그래머가 멀티 플랫폼 코드를 직접 개발 유지하는 데 한계치 도달
- 필요성: 문법 모호성 검증, 메모리 레지스터 할당 위치, 연산 흐름 최적화를 자동 수행하여 개발자 개입 없이 다중 플랫폼 네이티브 실행 속도 보장 필수

---

## Ⅱ. 구조 및 구성요소 (전체 아키텍처 맵)

```text
Source -> [Front-end (언어 종속 분석)] -> IR (중간언어) -> [Back-end (기계 종속 합성)] -> Machine Code
               |                                                 |
               +------------- Symbol Table / Error Handler ------+
```

| 구성요소 | 핵심 역할 | 산출물 및 특징 |
|:---|:---|:---|
| Front-end (전반부) | 특정 언어별 입력 소스코드의 문법적 타당성 스캔 및 검사 | 어휘/구문/의미 분석 $\rightarrow$ 공용 중간 코드(IR) 출력 |
| Back-end (후반부) | 타겟 하드웨어 환경(CPU 레지스터, 명령어셋) 특화 목적 코드 생성 | IR 코드 최적화 $\rightarrow$ 타겟 어셈블리/목적 코드 출력 |
| Symbol Table | 변수, 함수명, 타입 속성 및 스코프 정보를 해시 맵 형태로 전 단계 보관 관리 | 구문/의미 분석 단계 중복 선언 검사 및 타입 일치 제공 |
| Error Handler | 컴파일 파이프라인 스텝별 구문/타입 불일치 감지 및 에러 라인 번호 복구 | 파서 패닉 모드(Panic Mode) 가동 시 다음 토큰부터 복구 |

> 요약: 컴파일러는 언어 분석 프론트엔드와 기계어 합성 백엔드로 분리되며, 보조 장치인 심볼 테이블이 전 단계를 관통하여 문맥 정보를 공급한다.

---

## Ⅲ. 단계별 동작원리 및 파이프라인 흐름도

```text
소스코드 -> (1) 어휘 분석 -> (2) 구문 분석 -> (3) 의미 분석 -> (4) 중간코드 생성 -> (5) 최적화 -> (6) 목적코드 생성 -> 기계어
(산출물)     Token Stream      AST (구문 트리)   Decorated AST       IR / 3-Address Code  Optimized IR      Assembly Code
```

| 단계 구분 | 처리 내용 및 변환 동작 | 검사 기법 및 주요 감지 오류 |
|:---:|:---|:---|
| 1. 어휘 (Lexical) | 전체 문자열을 정규표현식 매칭 기반 의미 최소 단위(Token) 열로 절단 | 정의되지 않은 특수문자 삽입 오류 (Lexical Error) |
| 2. 구문 (Syntax) | 토큰 스트림이 문맥 자유 문법(BNF) 배열에 일치하는지 확인해 AST 노드 구성 | 괄호 짝 불일치, 구문 마침 세미콜론 누락 (Syntax Error) |
| 3. 의미 (Semantic)| AST 뼈대와 심볼 테이블 속성을 대조해 타입 호환성과 연산 타당성 검증 | 배열 인덱스 초과, 미선언 변수/함수 호출, 타입 캐스팅 불일치 |
| 4. 중간코드 (IR) | 분석 논리를 3-주소 코드(3-Address Code) 등 가상 기계 공통 언어로 변환 | 타겟 종속성(의존도) 분리 지점 확보 (오류 검출 아님) |
| 5. 최적화 (Optimize)| 반복문 루프 전개, 도달 불가능 데드 코드 삭제 등 공통 서브 연산 감축 | 프로그램 실행 지연시간 감소 및 분기 간소화 |
| 6. 생성 (Generate)| 타겟 인스트럭션 셋 아키텍처(ISA) 매핑 및 하드웨어 레지스터 최종 할당 | 타겟 기계어/어셈블리어 바이너리 빌드 (메모리 오버플로우 한계) |

> 요약: 어휘(Type 3 $\rightarrow$ 토큰), 구문(Type 2 $\rightarrow$ 트리), 의미(Type 1 $\rightarrow$ 타입) 논리를 거치며 문법을 통제하고, IR 포맷 변환 후 하드웨어 네이티브 코드로 찍어낸다.

---

## Ⅳ. 특징 및 아키텍처 분리 모델 비교

| 비교 축 | 단일 패스 (Single-pass) 일체형 구조 | 다중 패스 (Multi-pass) 및 IR 구조 분리 | 도입 설계 기준 |
|:---|:---|:---|:---|
| 파이프라인 결합 | 전 단계가 메모리에 동시 상주하며 1회 스캔(루프)으로 최종 바이너리 즉시 배출 | 각 단계가 산출물(IR 등)을 분리 저장하고 독립 모듈 형태로 파이프라인 수행 | 컴파일 장비 메모리 한계 vs 확장성 요구 |
| 주요 강점 | 컴파일 소요 시간 단축 및 파서 구현 단순함 | 강력한 알고리즘 최적화 적용 및 이기종 CPU 아키텍처 이식(Retargetable) 확장 우수 | 타겟 머신 런타임 최적화 깊이 |
| 적용 사례/트렌드 | 초기 파스칼 언어, 경량 V8 JIT 컴파일러 초기 스크립트 대응 | 최신 LLVM 기반 프레임워크 (Clang, Rust), 범용 GCC 아키텍처 | 플랫폼 하드웨어 독립 생태계 구축 여부 |

> 요약: 최근의 상용 컴파일러 생태계는 단축된 컴파일 시간보다 타겟 실행 바이너리의 압도적 속도 최적화 성능과 이기종 모바일 칩 지원이 절실하여 다중 패스(IR) 구조를 표준 채택한다.

## Ⅴ. 심화 비교 및 최적화 리스크 통제

| 최적화 유형 비교 | 최적화 적용 원리 및 예시 적용점 | 수행 목적 | 측정 지표 (KPI) |
|:---|:---|:---|:---|
| 기계 독립적 최적화 (Front/IR 영역) | 공통 부분식(Subexpression) 제거, 함수 인라이닝(Inlining), 상수 폴딩 | 연산 횟수 자체 논리 감축을 통한 소스 코드 구조 간소화 | 중간 코드(IR) 내 실행 명령어 라인 수 15% 단축 |
| 기계 종속적 최적화 (Back-end 영역)| 그래프 색칠(Graph Coloring) 기법 기반 레지스터 재할당, 파이프라인 해저드 지연스톨(Stall) 방지 재배치 | 타겟 CPU 아키텍처 클럭/캐시 구조 밀착을 통한 지연시간 최소화 | 타겟 실행 파일 IPC(명령어 처리량) 20% 상승 |

> 요약: 최적화 단계 또한 아키텍처와 무관한 소스 구조 축소(IR 단계)와 특정 하드웨어 자원 점유 효율 극대화(기계어 단계)로 명확히 분리 책임진다.

| 리스크 | 발생 원인 | 대응 통제 방안 | 확인 지표 |
|:---|:---|:---|:---|
| N×M 컴파일러 중복 생태계 비용 폭발 | 언어 N개와 지원 타겟 CPU M개 조합 시 N×M개의 일체형 컴파일러 백지 제작 공수 발생 | LLVM 도입: IR 포맷 공통화로 프론트(N개)+백엔드(M개) 결합, $N+M$ 복잡도로 설계 억제 | 신규 아키텍처(ARM) 포팅 소요 공수(MM) 단축 |
| 구문 에러 감지 시 연쇄 파싱 붕괴 | 한 번의 Syntax Error 위치에서 AST 트리가 끊어져 이후 올바른 코드까지 모두 검사 실패 마비 현상 | 파서의 Panic Mode Error Recovery(문장 끝 세미콜론까지 무시 후 파싱 스캔 재개) 전략 가동 | 1회 1스캔 당 독립적 문법 오류 다중 검출 건수 비율 |

> 요약: 다중 플랫폼 확장 비용 리스크는 LLVM 허브 앤 스포크 모델로 차단하고, 컴파일 오류 마비 현상은 파서 복구 로직으로 억제한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLVM 기반 다중 언어 플랫폼 통합망: 사내 특화 DSL이나 신규 스크립트 제작 시 전 과정을 코딩하지 않고 프론트엔드 파서만 제작하여 LLVM IR로 인도, x86/ARM 등 전 백엔드 바이너리를 무비용으로 자동 확보
2. 정적 분석기(SAST) 파이프라인 재활용: 소스코드 보안 취약점 진단 도구를 정규식(문자열 검색)에만 의존하지 않고, 컴파일러 Front-end의 AST 구문 트리 횡단 및 심볼 스코프 검사를 차용하여 SQL 인젝션 경로 탐지 정확도 95% 이상 제고
3. AOT 및 JIT 하이브리드 프로파일 연동: Android ART 런타임처럼 인스톨 시점에 기계 독립적 1차 AOT(사전 컴파일)를 수행하고, 자주 불리는 핫스팟(Hot Spot) 코드는 런타임 JIT가 심화 머신 종속 최적화를 주입하는 하이브리드 아키텍처 전개

**결론 (2줄):**
- 기술사 판단: 컴파일러 6단계 파이프라인 구조는 중앙의 IR(Intermediate Representation)을 쐐기로 삼아 언어 논리와 CPU 칩셋 종속성을 강하게 디커플링(Decoupling)한 소프트웨어 아키텍처 설계의 교과서적 모범이다.
- 향후 방향: 전통적인 AOT 정적 컴파일을 넘어서, 실행 중 수집된 프로필(Branch Predict) 데이터를 역피드백하여 동적 기계 코드를 재최적화하는 PGO(Profile-Guided Optimization) 기법이 컴파일 성능 튜닝의 다음 패러다임이다.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "컴파일러의 단계별 구성 요소를 설명하시오" | 어휘 $\rightarrow$ 구문 $\rightarrow$ 의미 $\rightarrow$ 기계어 6단계 변환 표 | 심볼 테이블(Symbol Table)과 에러 핸들러 통제 구조 |
| 설계/비교형 | "LLVM 프레임워크 중간언어(IR) 도입 효과 설계" | 프론트-백엔드 데이터 흐름 차단 다이어그램 | Ⅴ의 기계 독립적/종속적 최적화 차이 및 $N+M$ 확장 트레이드오프 |

> 요약: 컴파일러 기초 단계형 문제는 6단계 산출물(Token$\rightarrow$AST) 진화 과정 서술에 집중하고, 현대 아키텍처 장점 문제 시 IR 분리 구조 기반 유지보수성 확장 논리로 방어한다.
