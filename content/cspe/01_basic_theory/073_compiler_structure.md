## 미리 알고가기

- 토큰(Token): 키워드, 식별자, 연산자처럼 어휘 분석기가 만든 최소 의미 단위임
- AST(Abstract Syntax Tree): 문법 구조에서 불필요한 구분 기호를 줄인 추상 구문 트리임
- 심볼 테이블: 식별자의 타입, 범위, 주소 정보를 저장하는 표임
- IR(Intermediate Representation): 최적화와 코드 생성에 사용하는 중간 표현임
- 전단부/후단부: 언어 분석 중심 단계와 타깃 기계 코드 생성 단계를 나눈 경계임

## Ⅰ. 개요

- **정의/개념**: 컴파일러는 고급 언어 소스 코드를 분석하고 중간 표현을 최적화해 실행 가능한 목적 코드로 바꾸는 번역 시스템임
- **배경/필요성**: 소스 코드를 실행 가능한 목적 코드로 바꾸기 위해 문법 검증·의미 검사·기계 특화 최적화 단계가 필요함

## Ⅱ. 특징

- 전단부는 언어 문법과 의미를 검증하고 후단부는 타깃 아키텍처에 맞춰 코드를 생성함
- 단계별 산출물이 토큰, AST, IR, 목적 코드로 바뀌며 오류 위치를 좁혀 진단함
- 심볼 테이블을 공유해 선언, 범위, 타입 정보를 일관되게 관리함
- IR을 기준으로 여러 언어와 여러 하드웨어를 분리해 확장성을 높임

## Ⅲ. 종류 및 비교

| 단계 | 입력 | 출력 | 핵심 판단 | 대표 오류 |
|:---|:---|:---|:---|:---|
| 어휘 분석 | 문자 스트림 | 토큰 | 문자 패턴 분리 | 잘못된 문자, 토큰 오류 |
| 구문 분석 | 토큰 | AST | 문법 규칙 일치 | 괄호·세미콜론 오류 |
| 의미 분석 | AST | 속성 AST | 타입·범위 검사 | 미선언 변수, 타입 불일치 |
| 최적화 | IR | 최적화 IR | 중복·불필요 연산 제거 | 경고, 최적화 제약 |
| 코드 생성 | IR | 목적 코드 | 명령어·레지스터 배치 | 타깃 제약 위반 |

> 요약: 어휘는 단어, 구문은 구조, 의미는 타입과 범위를 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 렉서 | 문자 입력을 토큰 스트림으로 변환함 |
| 파서 | 토큰을 문법 규칙에 맞춰 AST로 구성함 |
| 의미 분석기 | 심볼 테이블로 타입과 범위 오류를 찾음 |
| 최적화기 | IR 수준에서 불필요한 계산과 이동을 줄임 |
| 코드 생성기 | 타깃 ISA에 맞는 명령과 레지스터를 배치함 |

```text
[ 컴파일러 파이프라인 ]
Source -> Lexer -> Tokens -> Parser -> AST -> Semantic -> IR -> Optimizer -> CodeGen -> Object
```

> 요약: 컴파일러는 소스를 단계별 중간 표현으로 낮추며 오류 진단과 최적화를 분리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 토큰화   | --> | AST 생성 | --> | 의미 검사 | --> | 코드 생성 |
+----------+     +----------+     +----------+     +----------+
```

1. **토큰화**: 정규 패턴으로 문자열을 토큰 단위로 분리함
2. **구조화**: 파서가 문법 규칙에 따라 AST를 생성함
3. **검증/변환**: 타입·범위를 확인하고 IR로 낮춤
4. **최적화/생성**: IR을 줄이고 타깃 기계 명령으로 변환함

> 요약: 전단부 검증이 정확해야 후단부 최적화와 코드 생성이 의미 있는 목적 코드를 만듦.

## Ⅵ. 실무 적용 및 유의점

1. 최적화 옵션은 성능을 높이지만 디버깅을 어렵게 하고 실행 타이밍을 바꾸므로 릴리스 빌드와 테스트 빌드를 분리해 검증함
2. 컴파일 오류 보고는 중단만 하지 말고 복구 토큰 기준으로 이어서 분석해 오류 위치와 개수를 함께 제공함

## Ⅶ. 결론

- 컴파일러 구조는 언어 검증과 기계 최적화를 분리해 정확한 오류 진단과 이식 가능한 코드 생성을 달성함

## 작성 근거(검토용)

- 개요는 분석, 최적화, 목적 코드 생성을 포함해 컴파일러의 전체 책임을 드러냄
- 특징은 전단부/후단부 분리, 단계별 산출물, 심볼 테이블, IR을 구조 선택의 핵심으로 선정함
- Ⅲ은 입력, 출력, 판단, 오류를 단계별로 배치해 컴파일 파이프라인을 추적하도록 구성함
- 구조 도식은 소스에서 목적 코드까지의 흐름이 컴파일러 구조의 중심임을 보여줌
- 유의점은 최적화와 오류 복구를 컴파일러가 개발 생산성과 운영 안정성에 영향을 주는 지점으로 선정함
