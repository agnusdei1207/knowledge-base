## Ⅰ. 개요
- **정의**: 고급 언어 소스 코드를 기계어로 변환하는 번역기의 단계별 파이프라인 아키텍처임
- **배경/필요성**: 하드웨어 독립 개발 -> 다중 타겟 플랫폼 코드 생성을 자동화하는 체계적 구조 요구
- **비유**: 외국어 원서를 단어 분리 -> 문장 구조 파악 -> 번역문 작성 순서로 옮기는 번역 공정

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프론트엔드/백엔드 분리 원리 | 중간 표현(IR) 기반 모듈화 | 인터프리터와 혼동 금지 |
| 단계별 변환 메커니즘 | Lexer->Parser->Semantic->IR->Opt->CodeGen | 최적화 패스 위치를 정확히 명시 |

> 요약: 소스 코드를 분석·변환·최적화하여 실행 가능한 기계어를 생성하는 다단계 번역 시스템임

## Ⅱ. 구성요소
```text
+--------+   +--------+   +--------+   +--------+   +--------+
| Lexer  |-->| Parser |-->| Semant |-->| Optim  |-->| CodeGn |
| (Token)|   | (AST)  |   | (IR)   |   | (IR')  |   | (Obj)  |
+--------+   +--------+   +--------+   +--------+   +--------+
  Front-End                              Back-End
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 어휘 분석기(Lexer) | 정규표현식으로 소스를 토큰(식별자·키워드·리터럴) 단위로 분할 | 단어 사전 |
| 구문 분석기(Parser) | 문법 규칙에 따라 토큰 열을 AST로 구조화 (LL/LR 상세 -> 074 참조) | 문장 해석기 |
| 의미 분석기 | 타입 검사·스코프 해석·심볼 테이블 관리로 의미적 오류 검출 | 교정 편집자 |
| 중간 코드 생성/최적화 | 플랫폼 독립 IR(SSA 등) 생성 후 상수 폴딩·루프 최적화 적용 | 초안 다듬기 |
| 코드 생성기 | 레지스터 할당·명령어 선택으로 타겟 아키텍처 기계어 출력 | 최종 인쇄 |

> 요약: Lexer->Parser->의미분석(프론트엔드)과 IR최적화->코드생성(백엔드)의 5단 파이프라인임

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| Tokenize | -> | Build    | -> | Optimize | -> | Emit     |
| Source   |    | AST + IR |    | IR Passes|    | MachCode |
+----------+    +----------+    +----------+    +----------+
```

1. **토큰화** — 소스 문자열을 정규표현식 매칭으로 토큰 스트림으로 분리함
2. **구조 분석** — 파서가 AST를 구축하고 의미 분석기가 타입 정합성·스코프를 검증함
3. **IR 최적화** — 3-주소 코드/SSA 형태 IR에 데드코드 제거·인라이닝 등 다중 패스 적용
4. **기계어 출력** — 타겟 ISA(x86/ARM 등)에 맞춰 레지스터 할당 후 오브젝트 코드 생성함

> 요약: 토큰화 -> AST/IR 구축 -> 다중 패스 최적화 -> 타겟 기계어 출력의 4단계 변환 절차임

## Ⅳ. 문제점
- [다중 타겟 비용]: CPU(x86/ARM/RISC-V)마다 백엔드를 별도 구현해야 하는 개발·유지보수 부담
- [빌드 시간 증가]: 최적화 패스 수 증가(LLVM 기준 200+ 패스) 시 대규모 프로젝트 빌드 10분+ 소요
- [런타임 최적화 한계]: 정적 컴파일은 실행 시점 프로파일 정보 미반영으로 최적화 상한 존재

> 요약: 타겟 다양성, 빌드 시간, 정적 분석 한계가 현대 컴파일러의 3대 병목임

## Ⅴ. 개선방안
1. 단기: LLVM IR 등 공통 중간 표현을 채택하여 프론트엔드/백엔드 조합을 M+N으로 축소
2. 중기: PGO(Profile-Guided Optimization)로 실행 프로파일을 빌드에 반영, 핫 경로 최적화율 15~30% 향상
3. 장기: ML 기반 자동 튜닝(AutoPhase 등)으로 최적화 패스 순서·조합을 자동 탐색

- [빌드 시간 과다]: 증분 컴파일·분산 빌드(distcc) 도입 -> 전체 빌드 대비 80%+ 시간 절감 (지표: 빌드 시간 ≤ 2분)

> 요약: 공통 IR -> 프로파일 기반 최적화 -> ML 자동 튜닝 순으로 다중 타겟·성능·빌드 문제를 해소함

## Ⅵ. 전망
- 향후 발전 방향: GPU/NPU/양자 가속기 등 이기종 타겟을 통합 지원하는 MLIR 기반 컴파일러 프레임워크 확산
- 기술사적 판단: AI 워크로드 증가로 TVM·XLA 등 도메인 특화 컴파일러가 범용 컴파일러와 병행 성장 중
- 기술사 제언: 신규 하드웨어 도입 시 컴파일러 백엔드 지원 성숙도를 선행 평가 기준에 포함할 것
