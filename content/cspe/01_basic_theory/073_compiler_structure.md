## 미리 알고가기

- 토큰: 어휘 분석 결과의 최소 의미 단위임
- AST: 구문 구조를 표현하는 추상 구문 트리임
- IR: 최적화와 코드 생성을 위한 중간 표현임

## Ⅰ. 개요

- **정의/개념**: 컴파일러는 고급 언어 소스 코드를 어휘 분석, 구문 분석, 의미 분석, 중간 코드 생성, 최적화, 목적 코드 생성 단계를 거쳐 실행 가능한 코드로 변환하는 시스템임
- **배경/필요성**: 사람이 이해하기 쉬운 언어와 기계가 실행하는 명령 사이에는 큰 추상화 간격이 있으므로 체계적인 변환 파이프라인이 필요함

## Ⅱ. 특징

- 단계별 책임이 분리되어 오류 위치와 원인을 추적하기 쉬움
- 앞 단계 산출물이 뒤 단계 입력이 되는 파이프라인 구조임
- 의미 분석과 최적화 품질이 실행 효율과 안정성을 좌우함
- 언어 기능이 늘수록 문법과 타입 체계 복잡도가 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 어휘 분석 | 구문 분석 | 의미 분석 |
|:---|:---|:---|:---|
| 입력 | 문자 스트림 | 토큰열 | AST |
| 출력 | 토큰 | 파스 트리/AST | 타입 정보, 오류 |
| 핵심 목적 | 패턴 인식 | 구조 확인 | 의미 일관성 검증 |
| 대표 기법 | DFA, regex | LL/LR 파싱 | symbol table, type check |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Lexer | 문자 스트림을 토큰화하고 어휘 규칙 적용부임 |
| Parser | 문법 규칙으로 구조를 만듦 AST 생성 중심임 |
| Semantic Analyzer | 타입과 스코프를 검증하고 오류 검출의 핵심임 |
| IR/Code Generator | 중간 표현과 기계 코드를 생성하고 실행 효율과 연결됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 소스입력 | --> | 토큰화 | --> | AST생성 | --> | 의미검사 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **소스입력**: 원시 프로그램 텍스트를 받음
2. **토큰화**: 예약어, 식별자, 리터럴로 분리함
3. **AST생성**: 문법 규칙에 따라 구조를 만든다
4. **의미검사**: 타입, 스코프, 선언 일관성을 확인함
5. **코드생성**: IR 최적화 후 목적 코드를 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 오류 메시지가 불친절할 수 있어 사용자가 원인을 파악하기 어려움
   - 해결방안: 위치 정보와 복구 전략을 강화하고 compile error usability로 검증함
2. 문제: 최적화가 의미를 깨뜨릴 수 있어 부정확한 변환은 오동작을 초래함
   - 해결방안: IR 검증과 테스트 스위트를 강화하고 miscompilation rate로 검증함
3. 문제: 언어 확장 시 단계 간 영향이 커 문법, 타입, 코드 생성 수정이 연쇄됨
   - 해결방안: IR와 단계 경계를 명확히 유지하고 change impact size로 검증함

## Ⅶ. 적용 사례

- 범용 프로그래밍 언어: C, Java, Rust 컴파일러가 대표적임, 확인 지표는 컴파일 정확도와 속도임
- DSL 엔진: 도메인 규칙을 실행 코드로 변환함, 확인 지표는 표현력과 오류 검출력임
- SQL/쿼리 최적화기: 구문 트리를 실행 계획으로 바꿈, 확인 지표는 실행 성능임

## Ⅷ. 결론

컴파일러 구조의 핵심은 단계를 나누어 의미를 점진적으로 구체화하는 데 있으므로, 앞단 오류 검출과 뒷단 코드 품질을 함께 관리해야 함.
