## 미리 알고가기

- 토큰(Token): 키워드, 식별자, 연산자처럼 어휘 분석기가 만든 최소 의미 단위임
- 정규표현식(Regular Expression): 토큰의 문자 패턴을 정의하는 규칙임
- 결정적 유한 오토마타(DFA): 정규표현식으로 정의한 패턴을 상태 전이로 인식하는 처리 모델임
- 추상 구문 트리(AST): 문법 구조에서 불필요한 구분 기호를 줄인 트리임
- 심볼 테이블: 식별자의 타입, 범위, 주소 정보를 저장하는 표임
- 중간 표현(IR): 최적화와 코드 생성에 사용하는 내부 코드 형식임
- 명령어 집합 구조(ISA): 목적 코드가 따르는 프로세서 명령어와 레지스터 규약임
- 전단부/후단부: 언어 분석 중심 단계와 타깃 기계 코드 생성 단계를 나눈 경계임
- 동기화 토큰: 구문 분석 오류 뒤에서 분석을 재개할 기준 구분자임
- 함수 인라이닝·루프 변환: 함수 호출을 본문으로 치환하는 최적화와 반복 구조를 바꾸는 최적화임

## 작성 근거(검토용)

- 개요는 분석, 최적화, 목적 코드 생성을 포함해 컴파일러의 전체 책임을 드러냄
- 특징은 전단부/후단부 분리, 단계별 산출물, 심볼 테이블, IR을 구조 선택의 핵심으로 선정함
- Ⅲ은 전단부와 후단부를 의존 대상·핵심 산출물·오류 유형 3개 축으로 비교해 구조 분리 근거를 보여줌
- Ⅳ는 전단부·심볼 테이블·중간 표현·최적화기·후단부의 정적 역할과 공유 관계를 설명함
- Ⅴ는 어휘·구문·의미 분석부터 코드 생성까지 단계별 입력·출력·핵심 처리를 절차 순서로 보여줌
- 실무 사례는 최적화와 오류 복구가 실행 비용과 복구 품질을 좌우하는 지점을 검증함
- 문장별 5회 전수 검수 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정했음

## Ⅰ. 개요

- **정의/개념**: 컴파일러는 고급 언어 소스 코드를 분석하고 중간 표현을 최적화해 실행 가능한 목적 코드로 바꾸는 번역 시스템임
- **배경/필요성**: 고급 언어는 사람이 이해하기 쉽지만 프로세서는 기계어만 실행하므로 번역 계층이 필요함

## Ⅱ. 특징

- 전단부는 언어 문법과 의미를 검증하고 후단부는 타깃 아키텍처에 맞춰 코드를 생성함
- 각 단계가 토큰, AST, IR, 목적 코드를 순차 생성해 오류가 발생한 처리 단계를 구분함
- 심볼 테이블을 공유해 선언, 범위, 타입 정보를 일관되게 관리함
- IR 공유로 새 언어·타깃 추가 시 나머지 전단부·후단부는 재사용함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전단부(Front-end) | 후단부(Back-end) |
|:---|:---|:---|
| 의존 대상 | 소스 언어 문법·의미 | 타깃 아키텍처 명령어 집합 |
| 핵심 산출물 | 검증된 IR | 목적 코드 |
| 대표 오류 유형 | 문법·타입 오류 | 레지스터 할당 실패 |

> 요약: 전단부는 언어 검증을 거쳐 IR을 만들고 후단부는 아키텍처 변환을 거쳐 목적 코드를 만듦.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 전단부 | 소스 검증과 IR 생성 단계 |
| 심볼 테이블 | 식별자 선언·타입·범위 저장소 |
| 중간 표현 | 전단부와 후단부의 공통 코드 |
| 최적화기 | 불필요한 연산·메모리 이동 제거기 |
| 후단부 | 타깃 명령 선택·레지스터 할당 단계 |

> 요약: 전단부와 후단부는 최적화기를 사이에 두고 IR을 공유하며 검증과 코드 생성을 분리함.

## Ⅴ. 원리 및 절차 흐름도

| 단계 | 입력 | 출력 | 핵심 처리 |
|:---|:---|:---|:---|
| 어휘 분석 | 문자 | 토큰 | 정규표현식·DFA 기반 토큰화 |
| 구문 분석 | 토큰 | AST | 문법 규칙 기반 AST 생성 |
| 의미 분석 | AST | 검증 AST | 심볼 테이블 기반 타입·범위 검사 |
| 중간 코드 생성 | 검증 AST | IR | 플랫폼 독립 표현 변환 |
| IR 최적화 | IR | 최적화 IR | 의미 보존 연산 축소 |
| 코드 생성 | 최적화 IR | 목적 코드 | 명령 선택·레지스터 할당 |

```text
[ 컴파일러 파이프라인 ]
소스 -> 어휘 분석 -> 토큰 -> 구문 분석 -> AST -> 의미 분석 -> 검증 AST
검증 AST -> 중간 코드 생성 -> IR -> 최적화 IR -> 코드 생성 -> 목적 코드
```

> 요약: 어휘·구문·의미 분석은 소스를 검증된 AST로 만들고 이후 단계는 이를 목적 코드로 변환함.

## Ⅵ. 실무 사례

1. 백엔드 서비스 빌드 파이프라인은 함수 인라이닝·루프 변환으로 최적화하고 실행 시간·목적 코드 크기로 최적화 효과를 가늠함
2. IDE 실시간 구문 검사기는 구문 분석 오류 발생 시 동기화 토큰까지 입력을 건너뛰어 복구하고 오류 위치 정확도·복구 성공률로 복구 품질을 판단함

## Ⅶ. 결론

- 컴파일러는 소스 분석과 기계어 생성을 중간 표현으로 분리하며, 변환 과정에서 프로그램 의미가 보존되어야 함
