## 미리 알고가기

- 토큰(Token): 키워드, 식별자, 연산자처럼 어휘 분석기가 만든 최소 의미 단위임
- AST(Abstract Syntax Tree): 문법 구조에서 불필요한 구분 기호를 줄인 추상 구문 트리임
- 심볼 테이블: 식별자의 타입, 범위, 주소 정보를 저장하는 표임
- IR(Intermediate Representation): 최적화와 코드 생성에 사용하는 중간 표현임
- ISA(Instruction Set Architecture): 목적 코드가 따르는 프로세서 명령어와 레지스터 규약임
- 전단부/후단부: 언어 분석 중심 단계와 타깃 기계 코드 생성 단계를 나눈 경계임

## 작성 근거(검토용)

- 개요는 분석, 최적화, 목적 코드 생성을 포함해 컴파일러의 전체 책임을 드러냄
- 특징은 전단부/후단부 분리, 단계별 산출물, 심볼 테이블, IR을 구조 선택의 핵심으로 선정함
- Ⅲ은 입력, 출력, 판단, 오류를 단계별로 배치해 컴파일 파이프라인을 추적하도록 구성함
- 구조 도식은 소스에서 목적 코드까지의 흐름이 컴파일러 구조의 중심임을 보여줌
- 최적화와 오류 복구는 목적 코드의 실행 시간과 오류 수정 반복 횟수에 영향을 줌

## Ⅰ. 개요

- **정의/개념**: 컴파일러는 고급 언어 소스 코드를 분석하고 중간 표현을 최적화해 실행 가능한 목적 코드로 바꾸는 번역 시스템임
- **배경/필요성**: 소스 코드를 실행 가능한 목적 코드로 바꾸기 위해 문법 검증·의미 검사·기계 특화 최적화 단계가 필요함

## Ⅱ. 특징

- 전단부는 언어 문법과 의미를 검증하고 후단부는 타깃 아키텍처에 맞춰 코드를 생성함
- 각 단계가 토큰, AST, IR, 목적 코드를 순차 생성해 오류가 발생한 처리 단계를 구분함
- 심볼 테이블을 공유해 선언, 범위, 타입 정보를 일관되게 관리함
- IR을 언어별 전단부와 타깃별 후단부 사이의 공통 표현으로 사용함

## Ⅲ. 종류 및 비교

| 단계 | 입력 | 출력 | 핵심 판단 | 대표 오류·제약 |
|:---|:---|:---|:---|:---|
| 어휘 분석 | 문자 스트림 | 토큰 | 문자 패턴 분리 | 잘못된 문자, 토큰 오류 |
| 구문 분석 | 토큰 | AST | 문법 규칙 일치 | 괄호·세미콜론 오류 |
| 의미 분석 | AST | 타입·범위가 반영된 AST | 타입·범위 검사 | 미선언 변수, 타입 불일치 |

> 요약: 어휘 분석은 문자에서 토큰을 만들고, 구문 분석은 토큰의 문법 구조를 확인하며, 의미 분석은 타입과 변수 범위를 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 전단부 | 어휘·구문·의미 분석으로 소스를 검증하고 IR을 생성함 |
| 심볼 테이블 | 식별자의 선언·타입·범위 정보를 분석 단계에 제공함 |
| 중간 표현 | 언어별 전단부와 타깃별 후단부를 분리하는 공통 코드임 |
| 최적화기 | IR 수준에서 불필요한 계산과 이동을 줄임 |
| 후단부 | 타깃 ISA에 맞는 명령을 선택하고 레지스터를 배치함 |

```text
[ 컴파일러 파이프라인 ]
소스 -> 어휘 분석 -> 토큰 -> 구문 분석 -> AST -> 의미 분석 -> IR -> 최적화 -> 코드 생성 -> 목적 코드
```

> 요약: 컴파일러는 소스를 토큰·AST·IR로 순차 변환해 오류 진단과 최적화를 분리함.

## Ⅵ. 실무 사례

1. 컴파일러 최적화는 함수 인라이닝·루프 변환을 적용하고 실행 시간·목적 코드 크기를 확인함
2. 컴파일 오류 복구는 동기화 토큰까지 분석을 이어가고 오류 위치 정확도·복구 성공률로 검증함

## Ⅶ. 결론

- 컴파일러는 언어 검증과 기계 최적화를 IR로 분리하고 단계별 산출물에서 오류 위치와 타깃 제약을 확인함
