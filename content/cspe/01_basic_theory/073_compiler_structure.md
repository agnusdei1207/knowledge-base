## 미리 알고가기

- 심볼 테이블($Symbol$ $Table$): 컴파일 과정 중 식별자(변수, 함수명 등)와 그에 매핑되는 타입, 주소 등 메타데이터를 저장하고 관리하는 중심 자료구조임
- 전단부($Front-end$)와 후단부($Back-end$): 소스 코드를 분석하여 중간 표현(IR)을 만드는 과정과, 이를 기반으로 목적 코드를 생성하는 하드웨어 종속 단계를 구분한 컴파일러 경계임
- 추상 구문 트리($AST$): 프로그램 소스 코드의 구조적 관계를 노드와 링크로 나타낸 나무 구조로, 괄호나 세미콜론 같은 불필요한 구문 기호들을 걷어낸 요약본임
- 타입 시스템($Type$ $System$): 변수와 연산의 데이터 형식 일치 규칙을 제어하고 검사하여 메모리 오염이나 예외를 사전 방지하는 의미 검증 규칙임

## Ⅰ. 개요

- **정의/개념**: 컴파일러는 인간이 이해하는 고급 언어 코드를 기계가 실행하는 저급 기계어로 번역하는 소프트웨어이며, 이를 위해 분석($Analysis$, 어휘/구문/의미)과 합성($Synthesis$, 최적화/목적코드 생성) 단계의 체계적인 파이프라인을 거치며 동작함
- **배경/필요성**: 개발자가 작성한 프로그램 텍스트는 바로 하드웨어 레지스터 연산으로 변환될 수 없으므로, 문법적 적합성 검증과 하드웨어 구조적 최적화($Optimization$)를 단계별로 나누어 안정적인 고속 기계 코드를 얻기 위해 필수적임

## Ⅱ. 특징

- 전단부(어휘, 구문, 의미 분석)는 하드웨어와 무관하게 언어의 명세 및 분석에 집중하고, 후단부(최적화, 코드 생성)는 타깃 CPU 아키텍처에 종속적인 기계어 효율에 최적화하여 컴파일러의 이식성을 극대화함
- 기호들의 범위와 스코프, 데이터 정의를 실시간으로 추적하는 '심볼 테이블'을 핵심 데이터 저장소로 전 단계가 공유하며 분석 일관성을 확보함
- 중간 코드($IR$)를 활용하여 하나의 프론트엔드 분석기로 복수 기기(Intel, ARM)의 기계어를 만들 수 있는 구조적 확장성을 제공함

## Ⅲ. 단계별 비교 및 파이프라인

| 컴파일 단계 | 입력 데이터 | 출력 결과물 | 핵심 동작 및 이론 | 탐지 가능한 컴파일 오류 |
|:---|:---|:---|:---|:---|
| **어휘 분석 (Lexical)** | 소스 코드 문자열 | 토큰 ($Token$) 스트림 | 정규 표현식, 유한 오토마타 ($DFA$) | 잘못된 문자 사용, 키워드 철자 오류 |
| **구문 분석 (Syntax)** | 토큰 스트림 | 추상 구문 트리 ($AST$) | 문맥 자유 문법 ($CFG$), 파싱 테이블 | 세미콜론 누락, 잘못된 문장 구조 |
| **의미 분석 (Semantic)** | 추상 구문 트리 | 속성 부여된 $AST$ | 심볼 테이블 참조, 타입 검사 | 미선언 변수 참조, 데이터 타입 불일치 |
| **중간 코드 생성 & 최적화** | 속성 $AST$ | 중간 코드 ($IR$) | 3-주소 코드 변환, 루프 최적화 | 논리적 제어 오루프 (경고 및 보정) |
| **목적 코드 생성 (CodeGen)** | 중간 코드 | 어셈블리/기계어 | 레지스터 할당, 하드웨어 명령어 매핑 | 하드웨어 제약 초과 오류 |

> 요약: 어휘 분석은 단어를, 구문 분석은 문장 구조를, 의미 분석은 문장의 모순(의미론적 규칙)을 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 어휘 분석기 ($Lexer$) | 문자열을 한 단어씩 읽어 예약어, 연산자, 식별자로 분리하고 의미를 부여함 |
| 구문 분석기 ($Parser$) | 토큰들을 문법 규칙에 맞추어 결합하고, 트리의 형상($AST$)으로 가공함 |
| 타입 검사기 | 의미 분석 단계에서 덧셈 대상인 두 변수의 실제 타입이 호환 가능한지 심볼 테이블을 열어 대조함 |
| 코드 최적화기 | 연산 횟수를 줄이고($Loop$ $Unrolling$, dead code 제거 등) 레지스터 사용을 압축함 |

```text
[ 컴파일러 전체 아키텍처 흐름 ]
[Source Code] -> (Lexer) -> [Tokens] -> (Parser) -> [AST] -> (Semantic) -> [Attributed AST]
                                                                                |
[Target Machine Code] <- (CodeGen) <- [Optimized IR] <- (Optimizer) <-----------/
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 문자열 입력  | --> | 토큰 분류분석| --> | 트리(AST)생성| --> | 타입/의미검증|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **단어 식별** — 소스 코드 원시 파일의 첫 문자부터 끝까지 읽으며 정규식 패턴 매칭(예: `[a-zA-Z_][a-zA-Z0-9_]*`는 식별자)을 시도하여 토큰 목록을 추출함
2. **구조 분석** — 추출된 토큰 스트림을 구문 분석기에 넣어, 재귀 하강 파싱 등 문법 규칙에 따라 기호들의 포함 관계인 파스 트리를 만들고 추상 구문 트리로 압축함
3. **타입/스코프 검증** — 심볼 테이블을 실시간 생성/업데이트하며, 변수의 선언 범위 유효성과 대입 연산 시 좌변과 우변의 데이터 형식 모순 여부를 검사함
4. **목적어 전환** — 검증 완료된 트리로부터 기계어와 일대일 대응이 편한 중간 코드(3-주소 코드 등)를 뽑아내고, CPU 아키텍처에 맞게 레지스터를 할당하며 최종 바이너리를 생성함

## Ⅵ. 실무 적용 및 유의점

1. 컴파일러 최적화 옵션(예: `gcc -O3`)을 너무 높게 잡으면 속도는 빨라질 수 있으나, 변수의 접근 순서나 미세 타이밍이 변경되어 컴파일러가 오동작을 일으키는 오컴파일($Miscompilation$)이 발생할 수 있으므로 임베디드나 실시간 제어 분야에서는 철저한 실기 테스트가 병행되어야 함
2. 어휘 분석과 구문 분석 오류 발생 시 단순 중단하기보다, 오류가 발생한 지점의 토큰을 임시 폐기하고 다음 구문(예: 다음 세미콜론)부터 파싱을 재개하는 '오류 복구($Error$ $Recovery$)' 규칙을 정밀하게 설계해야 개발자에게 친절한 에러 리포팅을 줄 수 있음

## Ⅶ. 결론

- 컴파일러는 기하학적 소스코드를 논리적 기계 코드로 연결해 주는 정밀한 지능 변환 엔진이며, 설계자는 전단부의 정교한 언어 유효성 평가 구조와 후단부의 하드웨어 친화적 최적화 파이프라인의 조화를 통해 고품질의 안전한 소프트웨어 개발 생태계를 정초해야 함
