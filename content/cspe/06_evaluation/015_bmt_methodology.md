# 📖 【암기용】 개념 완전 이해

> 목적: BMT를 SPEC·TPC 같은 표준 벤치마크와 혼동하지 않고, 공공조달·시스템 도입 전 후보 제품을 실측 검증하는 절차적 방법론으로 이해하게 만든다.

## 한눈에
- **개요**: BMT(Benchmark Test)는 공공조달 등 발주 전에 후보 제품·솔루션을 동일 조건에서 실측 시험해 제안 성능을 검증하는 절차적 방법론이다.
- **왜 필요한가**: 제안서의 성능 수치는 벤더 자체 측정치라 과장 가능성이 있고, 발주 후 부적합이 확인되면 사업 지연·재예산 비용이 발생한다.
- **핵심 직관**: 채용 시 이력서만 보지 않고 코딩 테스트로 실제 역량을 검증하는 것과 같다.

## 깊이 이해
- **배경·문제의식**: SPEC·TPC 같은 표준 벤치마크는 일반 워크로드 기준 수치이지, 발주 기관의 실제 데이터·시나리오와는 다르다.
- **배경·문제의식**: 국내 공공 SW사업에서는 제안 평가와 별도로 BMT를 통해 실측 근거를 확보하도록 요구되는 경우가 있다.
- **작동 원리**: 발주 기관이 평가 항목·배점·판정 기준을 사전 공개하고, 후보사가 동일 하드웨어·데이터·네트워크 조건에서 시나리오를 수행한다.
- **작동 원리**: 결과는 기능 충족률, TPS, 응답시간, 장애 복구시간, 운영 편의성 항목으로 정량 채점되어 사업자 선정 근거에 반영된다.
- **비유**: 여러 이사 업체를 불러 같은 짐, 같은 층수 조건으로 실제 견적·소요시간을 비교하는 것과 유사하다.
- **구체 예시**: 예시로 문서관리 솔루션 BMT에서 문서 100만 건 색인, 동시 사용자 500명, 검색 응답 p95 500ms 이하, 색인 지연 10분 이하를 조건으로 3개 후보사를 동일 환경에서 비교한다.
- **흔한 오해·주의점**: BMT는 벤더 시연회가 아니다.
- **흔한 오해·주의점**: 동일 하드웨어·데이터·시나리오·판정 기준이 보장되지 않으면 결과가 무효화될 수 있어 공정성 통제가 방법론의 핵심이다.

## 연결 개념
- 벤치마크 SPEC·TPC·LINPACK — 표준 벤치마크 결과를 BMT 시나리오 설계 참고자료로 활용
- 시스템 성능 지표 — TPS, 응답시간이 BMT 채점 항목의 핵심
- 정보 시스템 감리 — BMT 절차와 결과 증적이 감리 점검 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: BMT의 절차, 평가 항목 설계, 공정성 통제 방법론을 시험 답안으로 전개한다.
> 핵심: BMT는 성능 시연이 아니라 사전 공개된 배점·동일 조건·증적 관리를 갖춘 절차적 방법론이라는 점이 핵심이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: BMT는 발주 전 후보 제품을 동일 조건에서 시험해 기능·성능·운영성을 정량 채점하는 절차적 방법론이다.
> 2. **가치**: 제안서 수치와 실제 운영 조건 간 괴리를 줄이고 사업자 선정의 객관적 근거를 제공한다.
> 3. **판단 포인트**: 평가 항목 사전 공개, 동일 환경 구성, 결과 증적 보관 여부가 방법론의 신뢰성을 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| BMT 절차 이해 확인 | 평가 항목 설계, 동일 환경, 시나리오 실행 | 벤더 시연과 혼동 |
| 정량 채점 설계 역량 확인 | 배점표, TPS, 응답시간, 기능 충족률 | 정성 평가만 서술 |
| 공정성 확보 방법 확인 | 사전 공개, 동일 조건, 증적 보관 | 공정성 통제 절차 누락 |

> 요약: 이 문제는 BMT를 표준 벤치마크나 시연이 아니라 사전 설계된 채점 절차와 공정성 통제 방법론으로 설명할 것을 요구한다.

## Ⅰ. 개요 및 필요성

- 정의: 발주 전 후보 제품을 동일 조건에서 실측 시험해 정량 채점하는 절차적 방법론
- 배경: 제안서 성능 수치는 벤더 측정치이며 표준 벤치마크는 실제 업무 조건과 다름
- 필요성: 공공조달 사업자 선정의 객관적 근거 확보와 발주 후 부적합 리스크 사전 제거를 위해 필요

---

## Ⅱ. 구조 및 구성요소

```text
평가 요구 정의 -> 평가항목·배점 설계 -> 동일 환경 구성 -> 후보사 시나리오 실행 -> 채점·증적 관리
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 평가 항목·배점표 | 기능·성능·운영·비용 배점 정의 | 필수/선택/가점 구분, 사전 공개 |
| 동일 환경 | 하드웨어·데이터·네트워크 동일 제공 | 환경 차이 발생 시 즉시 기록 |
| 시나리오 | 실제 업무 패턴 기반 테스트 케이스 | 조회·등록·배치·장애 시나리오 |
| 결과 증적 | 로그·화면·리포트 보관 | 이의 제기·감사 대응 근거 |

> 요약: BMT 방법론은 사전 공개된 배점표, 동일 환경, 실업무 시나리오, 증적 관리로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구 분석 -> 평가항목 배점화 -> 환경·데이터 준비 -> 후보사별 순차 실행 -> 채점 집계 -> 결과 통보
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 필수 요구사항과 평가 항목 도출 | 요구사항 대응표 |
| 2 | 항목별 배점과 판정 기준 사전 공개 | 배점표 공식 공지 |
| 3 | 동일 하드웨어·데이터·네트워크 구성 | 환경 체크리스트 |
| 4 | 후보사별 동일 시나리오 순차 실행 | 실행 로그, 모니터링 화면 |
| 5 | 채점 집계와 결과·증적 보관 | 평가위원 서명, 리포트 보관 |

> 요약: BMT는 배점 사전 공개, 동일 환경 구성, 순차 실행, 증적 기반 채점 순서로 진행된다.

## Ⅳ. 특징

| 구분 | 표준 벤치마크(SPEC·TPC) | BMT | 수치 컬럼 |

| 결과 활용 | 하드웨어 선정 참고 | 사업자 선정 채점 근거 | 배점표 반영 |

> 요약: BMT는 표준 벤치마크와 달리 발주 기관의 실제 조건과 사업자 선정 채점에 직접 활용된다는 점이 특징이다.

| 운영/위험 | 발표 중심, 재현성 낮음 | 장애·운영 시나리오 포함 | SLA 요구 수준 |

|:---|:---|:---|:---|

| 시나리오 편향 | 특정 제품에 유리한 조건 설계 | 발주 요구 기반 공개 시나리오 검토위 운영 | 이의 제기 처리 건수 |
| 결과 재현 불가 | 설정·로그 미보관 | 실행 로그, 설정값, 화면 증적 의무 보관 | 증적 누락률 0% |

> 요약: BMT 신뢰성 리스크는 동일 조건 규정화, 공개 시나리오 검토, 증적 보관 의무화로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 기능 충족 | 필수 기능 통과율 100% | 체크리스트, 화면 증적 |
| 성능 충족 | 목표 TPS, 응답시간 p95 기준 충족 | 부하 테스트 리포트 |
| 공정성 | 환경 체크리스트 이상 0건 | 감사 로그, 참관 기록 |

> 요약: BMT 성공 여부는 필수 기능 통과, 성능 기준 충족, 공정성 이상 유무 증적으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. RFP 단계에서 BMT 평가 항목과 배점(기능·성능·운영·비용)을 사전 공개하고 판정 기준을 명문화함
2. 실제 운영 데이터 규모와 유사한 시나리오로 동일 하드웨어·네트워크 환경을 구성해 후보사별 조건 편차를 제거함
3. 실행 로그, 설정값, 모니터링 화면, 채점표를 증적으로 보관해 이의 제기·감사 대응 체계를 구축함

**결론 (2줄):**
- 기술사 판단: BMT는 표준 벤치마크의 대체가 아니라 발주 기관 실측 조건에서의 사업자 선정 검증 절차임
- 향후 방향: 클라우드 환경과 컨테이너 기반 재현 가능한 BMT 환경 자동 구성으로 공정성과 효율성이 함께 강화됨
