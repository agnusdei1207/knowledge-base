## 미리 알고가기

- BMT: 도입 후보 제품이나 시스템을 동일 조건에서 시험해 성능과 적합성을 비교하는 평가 활동임
- PoC: 특정 기술이나 제품이 요구 기능을 구현할 수 있는지 확인하는 검증 활동임
- 평가 시나리오: 후보 제품에 동일하게 적용할 업무 절차, 데이터, 부하 조건임
- 평가 항목: 성능, 기능, 안정성, 운영성, 비용처럼 후보를 판단할 기준임

## Ⅰ. 개요

- **정의/개념**: BMT 방법론은 제품·시스템 도입 후보를 동일한 업무 시나리오와 평가 기준으로 시험해 성능, 기능, 운영 적합성을 비교하는 절차임
- **배경/필요성**: 제안서와 표준 벤치마크만으로는 실제 업무 조건에서의 성능과 운영성을 알기 어려우므로, 동일 조건의 실증 시험이 필요함

## Ⅱ. 특징

- BMT는 후보 간 비교가 목적이므로 동일 데이터, 동일 부하, 동일 측정 기준을 유지해야 함
- 성능 수치뿐 아니라 장애 대응, 운영 편의성, 확장 조건, 비용을 함께 평가해야 함
- 평가 항목과 가중치를 사전에 확정하지 않으면 결과 해석이 공급자 주장에 흔들릴 수 있음
- BMT 환경이 실제 운영과 멀면 높은 점수가 도입 후 성능을 설명하지 못함

## Ⅲ. 종류 및 비교

| 판단 기준 | BMT | PoC |
|:---|:---|:---|
| 목적 | 여러 후보의 성능과 적합성을 비교함 | 특정 기술의 구현 가능성을 확인함 |
| 평가 방식 | 동일 조건에서 정량·정성 지표를 비교함 | 요구 기능 시나리오의 가능 여부를 확인함 |
| 산출물 | 평가 점수, 순위, 도입 판단 근거 | 기술 적용 가능성, 위험 목록 |
| 주의점 | 조건과 가중치를 사전에 고정해야 함 | 범위가 좁아 운영 성능을 단정하기 어려움 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 평가 기준 | 기능, 성능, 안정성, 운영성, 비용 항목과 가중치를 사전에 정의함 |
| 시험 환경 | 하드웨어, 네트워크, 데이터, 버전, 설정을 후보별로 동일하게 맞춤 |
| 시험 시나리오 | 실제 업무 흐름과 부하 패턴을 반영해 반복 가능한 절차로 작성함 |
| 결과 판정 | 측정값, 로그, 장애 기록, 운영 의견을 기준에 맞춰 점수화함 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 기준 정의    | --> | 환경 구성    | --> | 시험 수행    | --> | 결과 판정    |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 요구사항 정리 | --> | 평가표 작성  | --> | BMT 수행    | --> | 도입 판단    |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **요구사항 정리**: 업무 기능, 목표 성능, 운영 제약, 예산 조건을 정리함
2. **평가표 작성**: 항목, 지표, 가중치, 합격 기준을 사전에 확정함
3. **BMT 수행**: 후보별 동일 조건으로 기능, 성능, 장애 시나리오를 시험함
4. **도입 판단**: 점수와 위험을 비교해 우선협상 또는 도입 대상을 선정함

## Ⅵ. 실무 적용 및 유의점

1. 공공·금융 시스템 도입에서는 평가 기준이 사후 변경되면 공정성 문제가 생기므로 평가표와 원시 측정 데이터를 보관하고 항목별 점수 산출 근거로 확인함
2. 클라우드·SaaS BMT에서는 같은 인스턴스 스펙이라도 리전과 네트워크 조건이 결과를 바꿀 수 있으므로 region, instance type, latency, cost per transaction을 함께 확인함

## Ⅶ. 결론

BMT 방법론은 마음에 드는 제품을 고르는 절차가 아니라 동일 조건, 사전 기준, 원시 측정값으로 도입 판단을 방어하게 하는 평가 절차임.

## 작성 근거(검토용)

- 123회, 127회, 129회 기출 이력이 있어 절차형 답안으로 구성하고 공정성·재현성을 답안 축으로 잡음
- 일반론을 쓰지 않고 기준, 환경, 시나리오, 원시 데이터로 풀어씀
- 결론은 도입 판단의 방어 가능성으로 회수해 평가 방법론의 역할을 명확히 함
