# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 이중화 구성은 **용량 설계 표기** 모델로, 필요 용량(N) 대비 예비 유닛 규모를 N+1·2N·2N+1로 표준화한 것임. 각 표기가 몇 개의 동시 고장까지 허용하는지를 숫자로 정의함.
- **왜 필요한가**: "이중화했다"는 말만으로는 동시 고장 몇 개까지 버티는지 알 수 없음. N+1/2N/2N+1 표기가 있어야 가용성 목표(019)와 비용을 정량 매칭 가능.
- **핵심 직관**: N+1 = 축구팀 11명 + 교체선수 1명, 2N = 선발팀과 완전히 동일한 예비팀 통째로, 2N+1 = 예비팀 + 교체선수까지 추가.

## 핵심 용어 정리 (내부에 등장하는 것들)

023이 HA 구조(AA/AS)를, 024가 SPOF 제거를 다뤘으므로 여기서는 이중화 용량 설계 고유의 표기·등급 용어에 집중함.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| N | 서비스에 필요한 최소 유닛 수(피크 기준) | 축구 선발 11명 |
| N+1 (상위 키워드) | N에 예비 유닛 1개 추가, 1개 고장 허용 | 선발 11명 + 교체 1명 |
| 2N | N을 통째로 복제(2배), 그룹 전체 고장 허용 | 선발팀 + 완전 동일 예비팀 |
| 2N+1 | 2N + 예비 유닛 1개, 그룹 전체 + 1개 추가 고장 허용 | 예비팀 + 교체선수 |
| Tier 등급 | Uptime Institute DC 등급(I~IV) | 가용성 목표에 따른 시설 등급 |
| 장애 도메인 | 동일 물리 자원을 공유하는 범위(024 참조) | 같은 전원·랙·AZ |

## 깊이 이해
- **배경·문제의식**: 데이터센터 전원·냉방·UPS 설계에서 "이중화율"을 정량 표현할 표준이 필요해짐. Uptime Institute Tier 표준이 각 등급별 요구 이중화 수준(N, N+1, 2N)을 정의하면서 이 표기가 업계 표준이 됨.
- **작동 원리 — 각 구성의 정의**:
  - **N**: 필요 최소 유닛. 예비 없음. 1개만 고장 나도 용량 부족. (예: N=4면 서버 4대, 여유 0)
  - **N+1**: N에 예비 1개 추가. 1개 동시 고장까지 허용. (예: N=4 → 5대)
  - **2N**: N을 통째로 복제해 2그룹. 한 그룹 전체(N개)가 고장 나도 나머지가 100%. (예: N=4 → 8대)
  - **2N+1**: 2N에 예비 1개 추가. 한 그룹 전체 + 다른 그룹 1개까지 고장 허용. (예: N=4 → 9대)
- **Tier 등급과의 대응**: Tier I = N(이중화 없음), Tier II = N+1(부분 이중화), Tier III = N+1 또는 2N(동시 유지보수 가능), Tier IV = 2N 또는 2N+1(결함 허용).
- **비용 배수**: N 대비 N+1≈1.25배, 2N≈2배, 2N+1≈2.25배. 나인 등급(019)과 마찬가지로 허용 고장 개수가 늘수록 비용이 급증.
- **비유**: 자동차 → 스페어 타이어 1개(N+1), 예비 차량 1대(2N), 예비 차량 + 스페어 타이어(2N+1).
- **구체 예시**: 데이터센터 UPS 설계 — 서버룸 필요 전력 400kW → N=UPS 4대(각 100kW). N+1=5대(1대 점검 중에도 가동). 2N=8대(4대씩 A/B 두 계통, A 전체 장애 시 B가 100% 공급).
- **흔한 오해·주의점**: ① 2N이 N+1보다 항상 안전하지만 비용도 2배 → 비핵심 서비스에 2N은 과잉 투자. ② N+1은 동시 2개 고장 시 용량 부족 → "1개까지만"이라는 한계를 명확히. ③ 2N 구성이라도 두 그룹이 같은 장애 도메인(024)에 있으면 물리적 이중화가 무효화됨.

## 연결 개념
- **고가용성 설계 (023)**: AA는 2N에 가깝고 AS는 N+1에 가까운 대응 관계.
- **SPOF 제거 (024)**: 예비 용량 설계가 SPOF 제거를 정량화한 결과.
- **결함 허용 (029)**: TMR은 N=1, 2N+1=3 수준의 중복으로 결함 허용 용량 표기와 연계.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: N+1·2N·2N+1은 필요 용량(N) 대비 예비 유닛 규모를 표준화한 이중화 용량 표기임.
> 2. **가치**: 허용 동시 고장 개수를 숫자로 정의해 가용성 목표(Tier 등급)와 비용을 정량 매칭함.
> 3. **판단 포인트**: 서비스 중요도와 Tier 등급에 따라 N+1(1개 허용)·2N(그룹 허용)·2N+1(그룹+1) 중 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 표기법 정의 | N, N+1, 2N, 2N+1 각각의 유닛 수 계산 | "이중화 수준이 다르다"만 서술 |
| 허용 고장 개수 | 각 구성이 견디는 동시 고장 수 | 허용 고장 개수 미제시 |
| 비용-가용성 매칭 | Tier 등급·예산과의 연계 | 무조건 2N+1을 정답으로 제시 |

> 요약: 표기법 정의 + 허용 고장 개수 + Tier 등급·비용 매칭을 보여야 함.

## Ⅰ. 개요 및 필요성

- 개요: 필요 용량(N) 대비 예비 유닛 규모를 N+1·2N·2N+1로 표준화한 이중화 용량 설계 모델
- 배경: "이중화했다"는 정성적 표현으로는 동시 고장 허용 수를 알 수 없어 정량 표기 필요
- 필요성: 데이터센터 전원·냉방 설계와 Tier 등급(I~IV) 산정에 허용 고장 개수의 숫자 표기 필수

---

## Ⅱ. 구조 및 구성요소

```text
피크 부하 분석 -> 필요 유닛 수 N 산정 -> 목표 Tier 등급 확인
  -> N+1/2N/2N+1 구성 선택 -> 유닛 배치(그룹·장애 도메인 분리)
  -> 고장 주입 테스트 검증
```

| 구성요소 | 유닛 수(N=4 예시) | 허용 동시 고장 | Tier 대응 |
|:---|:---|:---|:---|
| N | 4대 | 0(여유 없음) | Tier I |
| N+1 | 5대 | 1개 유닛 | Tier II~III |
| 2N | 8대(4+4) | 1개 그룹(N개) 전체 | Tier III~IV |
| 2N+1 | 9대(4+4+1) | 1개 그룹 + 1개 유닛 | Tier IV |

> 요약: N→N+1→2N→2N+1 순으로 예비 유닛과 허용 고장 개수가 증가하고 Tier 등급에 대응함.

---

## Ⅲ. 동작원리 및 흐름도

```text
피크 부하 분석 -> N 산정 -> 목표 Tier 확인 -> 구성 선택
  -> 그룹 배치·물리 분리(024) -> 고장 주입 테스트 -> 검증 완료
```

1. 피크 부하 분석으로 필요 유닛 수 N을 산정하고 성장률을 반영해 여유를 둠
2. 목표 Tier 등급과 가용성(019)에 맞는 구성(N+1/2N/2N+1)을 선택함
3. 선택한 구성대로 유닛을 배치하되 2N 이상은 그룹 간 물리적 장애 도메인(024)을 분리함
4. 고장 주입 테스트로 설계 허용 고장 개수만큼 유닛을 제거해도 서비스가 유지되는지 실측 검증함

> 요약: N 산정 → Tier 기반 구성 선택 → 물리 분리 배치 → 고장 주입 테스트 검증 순으로 진행함.

---

## Ⅳ. 특징

- 정량 표기: "이중화"라는 모호한 표현 대신 허용 고장 개수(1개/N개/N+1개)를 숫자로 명시
- 비용 배수: N+1≈1.25배, 2N≈2배, 2N+1≈2.25배로 허용 고장 수에 비례해 비용 급증
- Tier 대응: Tier I=N, Tier II~III=N+1, Tier III~IV=2N/2N+1로 시설 등급과 직결
- N+1 한계: 동시 2개 고장 시 용량 부족 — 동시 다발 장애 확률이 높으면 2N 이상 필요
- 물리 분리 전제: 2N 그룹이 같은 장애 도메인(024)이면 물리적 이중화가 무효화됨

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | N+1 | 2N / 2N+1 | 선택 기준 |
|:---|:---|:---|:---|
| 예비 규모 | 예비 1개(최소 여유) | N개 전체 복제(+1) | 목표 Tier·허용 고장 개수 |
| 비용 | ≈1.25배(효율적) | ≈2~2.25배(고비용) | 예산 대비 다운타임 손실 |
| 적합 대상 | 중요도 중간 서비스, Tier II~III | 핵심 인프라(전원·냉방), Tier IV | 동시 다발 장애 발생 가능성 |

> 요약: 예산이 제한적이면 N+1, 핵심 인프라·최고 가용성 요구이면 2N 이상을 선택함.

**리스크·대응:**
- N 오산정: 피크 부하 과소 추정 → 성장률 반영 + 여유율 20% 설계 (지표: 실측 피크 대비 N 여유율)
- 물리적 미분리: 2N 그룹이 같은 랙·전원 배치 → 그룹 간 장애 도메인(024) 분리 정책 (지표: 그룹 간 동일 장애 도메인 0건)
- 과잉 투자: 비핵심 서비스에 2N+1 적용 → BIA 기반 중요도별 구성 차등(핵심→2N, 일반→N+1) (지표: 구성 등급-중요도 매핑 적합률)

**점검 지표:**
- 성능: 고장 주입 테스트 시 설계 허용 고장 수만큼 제거해도 서비스 정상 — 테스트 로그
- 운영: 2N 그룹 간 물리 분리 준수 + N 산정 정확도(여유율 20% 이내) — 배치도 감사·용량 리뷰

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 피크 부하 분석으로 N을 산정하고 성장률 20% 여유를 반영, 서비스 중요도·Tier 등급에 따라 N+1/2N/2N+1을 차등 적용함
2. 2N 이상 구성은 그룹 간 랙·전원·AZ를 물리적으로 분리해 장애 도메인(024) 공유를 방지함
3. 정기 고장 주입 테스트로 설계 허용 고장 수만큼 유닛 제거 시 서비스 정상을 검증하고 N 산정을 재조정함

**결론:**
- 기술사 판단: 이중화 구성은 허용 고장 개수와 비용을 정량 매칭해 N+1/2N/2N+1 중 선택해야 하며 물리적 분리가 전제임
- 향후 방향: 클라우드에서는 물리 유닛 대신 AZ·리전 단위로 N+1/2N 개념을 재해석하고 오토스케일링과 결합하는 방향으로 발전 중임
