# 📖 【암기용】 개념 완전 이해

> 목적: 동시 사용자 수·평균 응답시간·TPS 세 값이 하나의 공식으로 서로 역산 가능하다는 것을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 리틀의 법칙(L=λW)을 실무 용량 산정에 적용해 동시 사용자 수(L), TPS(λ), 평균 응답시간(W)을 서로 역산하는 계산법
- **왜 필요한가**: 부하테스트 도구는 흔히 동시 사용자 수(가상 사용자 수)를 입력받지만 SLA는 TPS로 표기되므로, 둘을 정확히 환산해야 테스트 설계와 SLA 목표가 일치
- **핵심 직관**: 회전문을 초당 몇 명이 통과하는지(TPS)와 회전문 안에 항상 몇 명이 있는지(동시 사용자 수)는 한 사람이 회전문을 통과하는 데 걸리는 시간(응답시간)으로 연결된다는 것과 같음

## 깊이 이해
- **배경·문제의식**: 부하테스트 스크립트를 "동시 사용자 500명"으로 설정했는데 실제 목표가 "TPS 500"이면, 응답시간에 따라 실제로 발생하는 부하 수준이 크게 달라져 테스트 결과가 목표와 어긋남
- **작동 원리**: 리틀의 법칙 L=λW를 응용해 TPS(λ) = 동시 사용자 수(L) / 평균 응답시간(W), 반대로 동시 사용자 수(L) = TPS(λ) × 평균 응답시간(W)로 상호 환산
- **비유**: 고속도로 톨게이트를 초당 통과하는 차량 수(TPS)와 도로 위에 항상 존재하는 차량 수(동시 사용자 수)는 차량 한 대가 도로 구간을 통과하는 데 걸리는 시간(응답시간)을 매개로 연결되는 것과 같음
- **구체 예시**: 예시로 목표 TPS가 500이고 평균 응답시간이 0.4초(400ms)라면 필요한 동시 사용자 수는 L=λW=500×0.4=200명이며, 반대로 부하테스트 도구에서 동시 사용자 200명, 평균 응답시간 0.4초로 측정되었다면 달성 TPS는 λ=L/W=200/0.4=500건/초로 역산 가능
- **흔한 오해·주의점**: 이 공식은 응답시간이 짧을수록 더 적은 동시 사용자로도 목표 TPS를 낼 수 있음을 의미하므로, 동시 사용자 수만 늘리면 TPS가 비례해서 오른다고 오해하면 안 되며 응답시간이 함께 고려되어야 함(수치는 예시이며 실제 값은 부하테스트로 검증 필요)

## 연결 개념
- 리틀의 법칙 — 이 계산법의 수학적 근거(L=λW)
- 시스템 성능 지표(TPS·응답시간) — 계산에 사용되는 두 원천 지표
- 성능 테스트(부하·스트레스·소크·스파이크) — 계산된 동시 사용자 수를 테스트 시나리오에 반영

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: TPS 계산 답안은 리틀의 법칙 기반 산식, 동시 사용자 수·TPS·응답시간 상호 환산 절차, 부하테스트 시나리오 적용 방법을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPS 계산은 리틀의 법칙(L=λW)을 응용해 동시 사용자 수(L), TPS(λ), 평균 응답시간(W)을 상호 환산하는 실무 공식이다.
> 2. **가치**: 부하테스트 도구의 동시 사용자 수 설정값과 SLA 목표 TPS를 응답시간을 매개로 정확히 일치시킬 수 있다.
> 3. **판단 포인트**: 동시 사용자 수를 늘려도 응답시간이 함께 증가하면 TPS는 비례해서 늘지 않으므로 응답시간 변화를 함께 검증해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산식 이해 및 적용 확인 | TPS=L/W, L=TPS×W (리틀의 법칙 응용) | 공식 유도 근거(리틀의 법칙) 없이 결과값만 제시 |
| 상호 환산 능력 확인 | 동시 사용자 수·TPS·응답시간 중 둘로 나머지 계산 | 세 값을 독립적인 값으로 서술 |
| 실무 적용 한계 이해 확인 | 부하 증가 시 응답시간 변화가 계산값에 영향 | 동시 사용자 수 증가가 항상 TPS 비례 증가로 이어진다고 서술 |

> 요약: 이 문제는 계산 결과보다 리틀의 법칙에 근거한 상호 환산 절차와 응답시간 변화 반영 여부를 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 리틀의 법칙을 응용해 동시 사용자 수·TPS·평균 응답시간을 상호 환산하는 실무 계산법
- 배경: TPS(λ) = 동시 사용자 수(L) / 평균 응답시간(W), 동시 사용자 수(L) = TPS(λ) × 평균 응답시간(W) 산식을 활용
- 필요성: 부하테스트 시나리오 설계와 SLA 목표(TPS)를 일치시키려면 응답시간을 매개로 한 정확한 환산이 필요

---

## Ⅱ. 구조 및 구성요소

```text
SLA 목표(TPS 또는 동시 사용자 수) 확인 -> 예상 평균 응답시간 산정
  -> 리틀의 법칙(L=λW) 적용 -> 나머지 변수 계산
  -> 부하테스트 시나리오 파라미터 설정 -> 실측 검증
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| TPS(λ) | 초당 완료 트랜잭션 목표치 | SLA 문서에 명시된 처리 목표 |
| 평균 응답시간(W) | 요청 시작~완료까지 평균 시간 | 실측 또는 목표 SLO 값 사용 |
| 동시 사용자 수(L) | 특정 시점 시스템 내 평균 존재 요청 수 | 부하테스트 가상 사용자 수 설정에 사용 |
| 환산 절차 | L=λW 공식으로 상호 계산 | 값 변경 시 재계산 필요 |

> 요약: TPS·응답시간·동시 사용자 수 중 둘을 알면 리틀의 법칙 공식으로 나머지 값을 산출한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
목표 TPS 또는 동시 사용자 수 확인 -> 예상 평균 응답시간 확보
  -> L=λW 계산 -> 부하테스트 도구에 파라미터 반영
  -> 테스트 실행 후 실측 TPS·응답시간 수집 -> 목표치와 비교 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | SLA 목표 TPS 또는 동시 사용자 수 확인 | 목표치 문서화 |
| 2 | 예상 평균 응답시간 확보(과거 실측 또는 목표 SLO) | 응답시간 근거 데이터 유무 |
| 3 | L=λW 공식으로 나머지 변수 계산 | 계산값 산출 근거 명시 |
| 4 | 부하테스트 실행 후 실측치와 계산값 비교 | 실측 TPS·응답시간과 목표 오차율 |

> 요약: 목표치와 예상 응답시간을 확보해 리틀의 법칙으로 필요 변수를 계산하고, 부하테스트 실측치로 검증한다.

## Ⅳ. 특징

| 구분 | TPS 목표로부터 사용자 수 산정 | 사용자 수 실측으로부터 TPS 역산 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 산식 | L=TPS×W | TPS=L/W | 예시: TPS 500, W=0.4s -> L=200명 |
| 활용 시점 | 부하테스트 시나리오 설계 단계 | 부하테스트 실행 결과 분석 단계 | 가상 사용자 수 파라미터 설정 |
| 전제 조건 | 목표 응답시간이 사전 정의됨 | 실측 응답시간이 안정적으로 측정됨 | 정상 상태(steady state) 가정 |
| 주의점 | 응답시간 목표 미달 시 재계산 필요 | 응답시간 급변 구간은 평균값 왜곡 가능 | p95 응답시간 병행 확인 권장 |

> 요약: 시나리오 설계 시엔 사용자 수를, 결과 분석 시엔 TPS를 리틀의 법칙으로 역산하며 두 방향 모두 응답시간이 매개 변수다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 이론 계산값 | 실측 부하테스트값 | 선택 기준 |
|:---|:---|:---|:---|
| 목적 | 테스트 시나리오 사전 설계 | 실제 시스템 성능 검증 | 설계 단계는 계산, 실행 단계는 실측 병행 |
| 정확도 | 응답시간 예상치에 의존 | 실제 자원 포화 시 응답시간 변화 반영 | 계산값과 실측값 괴리 시 병목 의심 |
| 활용 | 가상 사용자 수 파라미터 결정 | SLA 달성 여부 판정 | 반복 테스트로 두 값 수렴 확인 |

> 요약: 계산값은 테스트 설계의 출발점이며, 실측 부하테스트 결과와 비교해 응답시간 변화에 따른 괴리를 확인해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 시나리오 파라미터 오설정 | 동시 사용자 수와 TPS를 응답시간 반영 없이 임의 설정 | 리틀의 법칙 기반 환산 후 파라미터 설정 | 계산값과 실측값 오차율 |
| 응답시간 변화 미반영 | 부하 증가 시 응답시간 증가를 무시하고 선형 예측 | 단계적 부하 증가 테스트로 응답시간 변곡점 확인 | 부하 구간별 응답시간 추이 |
| 평균값 왜곡 | 이상치 포함된 평균 응답시간으로 계산 | p95 응답시간 병행 계산 및 비교 | 응답시간 분포, 이상치 비율 |

> 요약: 응답시간 변화를 반영하지 않은 채 시나리오를 설계하면 부하테스트 결과가 실제 목표와 어긋날 위험이 있다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 계산-실측 TPS 일치도 | 목표 오차율 이내(예: 10% 이내) | 부하테스트 결과 비교 |
| 응답시간 변곡점 파악 | 부하 증가에 따른 응답시간 급증 구간 문서화 | 단계적 부하 증가 테스트 |
| 시나리오 재현성 | 동일 파라미터로 반복 테스트 시 결과 일관성 | 반복 테스트, 통계 분석 |

> 요약: 도입 후 성공 여부는 계산-실측 TPS 일치도, 응답시간 변곡점 파악, 시나리오 재현성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 부하테스트 시나리오 설계 시 SLA 목표 TPS와 예상 응답시간으로 리틀의 법칙 기반 동시 사용자 수를 산정함
2. 테스트 실행 후 실측 동시 사용자 수·응답시간으로 달성 TPS를 역산해 목표치와 비교함
3. 부하 구간별로 단계적 테스트를 실시해 응답시간 변곡점을 파악하고 계산값 대비 괴리 원인을 분석함

**결론 (2줄):**
- 기술사 판단: TPS·동시 사용자 수·응답시간은 독립 값이 아니라 리틀의 법칙으로 연결된 값이므로 함께 검증해야 함
- 향후 방향: 부하테스트 자동화 파이프라인에 리틀의 법칙 기반 파라미터 계산기를 내장해 시나리오 설계 오류를 사전에 줄여야 함
