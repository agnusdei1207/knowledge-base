## 미리 알고가기

- TPS: 1초 동안 완료된 트랜잭션 수임
- 동시 사용자 수 $N$: 같은 시간대에 시스템을 사용하는 사용자 또는 VUser 수임
- 응답시간 $R$: 요청 후 응답 완료까지 걸린 시간임
- Think Time $Z$: 사용자가 다음 요청을 보내기 전 머무는 시간임
- Closed Workload: 고정된 사용자 수가 응답과 대기 시간을 반복하며 요청을 보내는 모델임

## Ⅰ. 개요

- **정의/개념**: TPS 계산은 동시 사용자 수, 응답시간, Think Time의 관계를 이용해 목표 처리량과 필요한 부하 수준을 산정하는 성능 평가 방식임
- **배경/필요성**: 접속자 수만으로 시스템 처리량을 말하면 사용자 행동과 응답 지연을 반영하지 못하므로, 부하 테스트와 용량 산정에 쓸 계산 기준이 필요함

## Ⅱ. 특징

- 폐쇄형 모델에서는 $TPS = \frac{N}{R + Z}$로 계산함
- 응답시간이 길어지면 같은 사용자 수에서도 사용자가 다음 요청을 늦게 보내므로 TPS가 선형 증가하지 않음
- Think Time을 0으로 두면 실제 사용자보다 과도한 요청률을 만들 수 있음
- 목표 TPS 산정은 단일 API가 아니라 업무 시나리오별 요청 비율과 트랜잭션 정의를 먼저 정해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 동시 사용자 기반 | 요청률 기반 |
|:---|:---|:---|
| 입력값 | 사용자 수, 응답시간, Think Time | 초당 요청 수 또는 트랜잭션 수 |
| 적합 상황 | 웹 사용자 행동을 재현하는 부하 시험 | API Gateway, 메시지 처리량 시험 |
| 장점 | 사용자 체류 시간을 반영함 | 목표 부하를 직접 제어하기 쉬움 |
| 주의점 | Think Time 설정이 결과를 크게 바꿈 | 사용자 행동과 체감 지연을 설명하기 어려움 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 트랜잭션 정의 | 무엇을 1건으로 셀지 정해 TPS 계산의 분모와 분자를 일관되게 함 |
| 동시 사용자 수 | 부하 발생기의 VUser 수 또는 실제 active user 수로 입력 부하를 표현함 |
| 응답시간 | 사용자 요청 주기를 늘리는 값이며 TPS 계산의 분모에 포함됨 |
| Think Time | 사용자의 읽기, 입력, 대기 시간을 반영해 실제 요청 간격을 표현함 |

```text
+-----------+     +-----------+     +-----------+
| 사용자 수 N  | --> | R + Z     | --> | TPS 계산   |
+-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 업무 정의    | --> | 변수 산정    | --> | TPS 계산    | --> | 시험 검증    |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **업무 정의**: 트랜잭션 단위와 업무별 요청 비율을 정함
2. **변수 산정**: $N$, $R$, $Z$를 실제 사용자 패턴이나 목표값으로 정함
3. **TPS 계산**: 폐쇄형 모델 산식으로 목표 또는 예상 TPS를 계산함
4. **시험 검증**: 계산값을 부하 테스트에서 측정한 TPS, RT, 오류율과 비교함

## Ⅵ. 실무 적용 및 유의점

1. 웹 업무 부하 테스트에서는 Think Time을 업무 화면 체류 시간에 맞춰야 하므로 access log와 RUM 데이터를 참고하고 실제 TPS와 session duration으로 확인함
2. API 처리량 산정에서는 트랜잭션 1건이 여러 내부 호출로 분해될 수 있으므로 외부 TPS와 내부 RPS를 구분하고 gateway RPS와 service별 call rate로 확인함

## Ⅶ. 결론

TPS 계산은 접속자 수를 처리량으로 바꾸는 단순 나눗셈이 아니라 사용자 대기 시간, 응답시간, 트랜잭션 정의를 맞춰 부하 시험 목표를 정하는 절차임.
