# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 벤치마크(SPEC·TPC·LINPACK)는 표준화된 워크로드로 하드웨어·시스템 성능을 동일 조건에서 측정해 비교 가능한 수치(SPECint·tpmC·FLOPS)로 표현하는 산업 표준 성능 척도(성능 지표는 001, 규모 산정 매핑은 013 참조)
- **왜 필요한가**: 벤더마다 다른 조건의 성능 주장을 그대로 믿을 수 없어, 공인 기관이 규정한 동일 워크로드·규칙으로 측정해야 서로 다른 장비를 공정하게 비교·선정할 수 있음
- **핵심 직관**: 자동차 연비를 각자 다른 도로에서 재면 비교 불가하므로, 공인된 표준 주행 코스(벤치마크)에서 같은 방식으로 측정해 등급표를 만드는 것과 같음

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 표기는 답안용 Ⅰ~Ⅵ의 표에 그대로 등장하므로 먼저 직관적으로 풀어 둔다. 상위 핵심 키워드는 **표준 워크로드 기반 성능 측정 지표(연산·트랜잭션·부동소수점)**이다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SPEC | 표준 성능 평가 기관·벤치마크 모음(CPU·Java·Web) | 공인 자동차 연비 시험 기관 |
| SPEC CPU 2017 | 프로세서 연산 성능 벤치마크(정수·부동소수점) | 코스별 가속·주행 성능 시험 |
| SPECint / SPECfp | 정수 연산 / 부동소수점 연산 성능 점수 | 시내 주행 / 고속 주행 연비 |
| TPC | 트랜잭션 처리 성능 평가 기관·벤치마크 | 결제 시스템 처리 속도 공인 시험 |
| TPC-C / tpmC | OLTP(주문 처리) 벤치마크 / 분당 처리 트랜잭션 | 매장 계산대의 분당 결제 건수 |
| TPC-H / QphH | 의사결정지원(OLAP) 복합 쿼리 벤치마크 / 시간당 쿼리 | 대량 데이터 분석 리포트 처리량 |
| $/tpmC | 처리 1단위당 비용(가격 대비 성능) | 결제 1건 처리에 드는 장비 원가 |
| LINPACK / HPL | 밀집 선형대수(연립방정식) 벤치마크 | 초대형 계산 문제 푸는 속도 시험 |
| FLOPS | 초당 부동소수점 연산 수(GFLOPS·PFLOPS) | 초당 수식 계산 횟수 |
| Rmax / Rpeak | LINPACK 실측 최대 성능 / 이론 최대 성능 | 실제 낸 최고 속도 / 카탈로그상 최고 속도 |
| TOP500 | LINPACK Rmax 기준 세계 슈퍼컴 순위 | 세계에서 가장 빠른 계산기 랭킹 |

## 깊이 이해
- **배경·문제의식**: 벤더의 "우리 서버가 2배 빠르다"는 측정 조건이 제각각이면 무의미함. SPEC·TPC·LINPACK은 워크로드·측정 규칙·공시 방법까지 규정해 재현·비교 가능한 수치를 보장함
- **작동 원리(어떻게+왜)**: SPEC CPU는 실제 응용 유사 프로그램 집합을 돌려 기준 머신 대비 상대 점수(SPECint·SPECfp)를 산출함. TPC-C는 주문·결제 트랜잭션 혼합을 규정 규칙으로 부하해 tpmC와 $/tpmC를 함께 공시(가격 대비 성능을 강제)함. LINPACK은 대형 연립방정식(밀집 행렬)을 풀며 FLOPS(Rmax)를 측정해 TOP500 순위를 매김. 각각 측정 대상(연산·트랜잭션·부동소수점)과 워크로드 성격이 달라 용도별로 선택해야 함
- **비유**: SPEC은 엔진 마력 시험, TPC는 계산대 처리 속도 시험, LINPACK은 초대형 계산 경주로, 같은 차라도 어떤 코스에서 재느냐에 따라 강점이 다르게 드러남
- **구체 예시**: OLTP DB 서버 선정에는 TPC-C(tpmC)·$/tpmC가, 대용량 분석·DW에는 TPC-H(QphH)가, HPC·시뮬레이션 클러스터에는 LINPACK(PFLOPS)이, 범용 애플리케이션 서버 CPU 성능에는 SPEC CPU 2017이 적합함(선정은 실제 워크로드로 BMT 검증 병행 필요, 015 참조)
- **흔한 오해**: 벤치마크 점수가 높다고 실제 업무 성능이 비례하지 않음. 표준 워크로드와 실제 워크로드가 다르면 괴리가 크므로, 벤치마크는 후보 선별·초기 사양 매핑에 쓰고 최종 확정은 자사 시나리오 BMT로 검증해야 함. Rpeak(이론)과 Rmax(실측)를 혼동하면 안 됨

## 연결 개념
- HW 규모 산정(013) — tpmC·SPEC 점수를 산정값과 장비 사양 매핑에 활용
- BMT(015) — 표준 벤치마크를 자사 워크로드 맞춤 시험으로 확장·검증하는 실무 절차
- 성능 지표(001) — 벤치마크가 측정하는 처리량·응답시간의 정의 기반

## Ⅰ. 개요 및 필요성

- 개요: 표준화된 워크로드로 하드웨어 성능을 동일 조건 측정해 비교 가능 수치로 공시하는 산업 표준
- 배경: 벤더별 상이한 측정 조건으로는 장비 성능을 공정 비교할 수 없음
- 필요성: 공인 기관(SPEC·TPC) 규칙으로 재현·비교 가능한 성능 근거를 확보해 선정·산정에 활용
- 한계: 표준 워크로드가 실업무와 달라 최종 확정은 자사 BMT 검증이 필요(015 참조)

---

## Ⅱ. 구조 및 구성요소

```text
표준 워크로드 정의 -> 측정 규칙·환경 규정 -> 시험 수행
  -> 종류별 지표 산출 분기: SPEC(연산 점수) / TPC(트랜잭션·가격) / LINPACK(FLOPS)
  -> 공인 기관 검증·공시 -> 장비 비교·선정 활용
```

| 구성요소 | 측정 대상 | 대표 지표 |
|:---|:---|:---|
| SPEC CPU 2017 | 프로세서 정수·부동소수점 연산 | SPECint, SPECfp |
| TPC-C | OLTP 트랜잭션 처리·가격성능 | tpmC, $/tpmC |
| TPC-H | 의사결정지원(OLAP) 복합 쿼리 | QphH |
| LINPACK(HPL) | 밀집 선형대수 부동소수점 연산 | FLOPS(Rmax), TOP500 |

> 요약: 벤치마크는 표준 워크로드·측정 규칙·종류별 지표·공인 검증으로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
평가자가 워크로드 성격 식별 -> 적합 벤치마크 선택 -> 규정 환경 구성·시험 수행
  -> 지표 산출(SPECint/tpmC/FLOPS) -> 공시값 비교 -> 자사 BMT로 최종 검증
```

- 1단계: 평가자가 대상 시스템의 워크로드 성격(연산·OLTP·분석·HPC)을 식별함
- 2단계: 평가자가 성격에 맞는 벤치마크(SPEC/TPC-C/TPC-H/LINPACK)를 선택함
- 3단계: 공인 규칙대로 환경을 구성해 시험을 수행하고 SPECint·tpmC·FLOPS 등 지표를 산출함
- 4단계: 평가자가 공시값으로 후보를 비교하고 자사 워크로드 BMT(015)로 실측 괴리를 검증함

> 요약: 평가자가 워크로드에 맞는 벤치마크를 선택·수행해 지표를 얻고 자사 BMT로 최종 검증함.

---

## Ⅳ. 특징

- 측정 대상이 종류마다 다름: SPEC은 프로세서 연산, TPC는 트랜잭션 처리, LINPACK은 부동소수점 연산을 잼
- 동일 조건 재현성을 보장함: 공인 기관이 워크로드·규칙·공시 방법을 규정해 벤더 간 공정 비교가 가능함
- TPC는 가격성능을 강제함: tpmC와 함께 $/tpmC를 공시해 성능뿐 아니라 비용 효율을 함께 드러냄
- 이론과 실측을 구분함: LINPACK은 Rpeak(이론)과 Rmax(실측)를 분리해 실효 성능을 명시함
- 실업무와 괴리가 존재함: 표준 워크로드가 자사 업무와 달라 점수가 실성능을 그대로 보장하지 않음

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SPEC CPU 2017 | TPC-C | TPC-H | LINPACK(HPL) |
|:---|:---|:---|:---|:---|
| 측정 대상 | 프로세서 연산 성능 | OLTP 트랜잭션 처리 | OLAP 복합 쿼리 | 부동소수점 연산 |
| 워크로드 성격 | 응용 유사 연산 집합 | 주문·결제 혼합 부하 | 대량 분석 쿼리 | 밀집 선형대수 |
| 대표 지표 | SPECint·SPECfp | tpmC·$/tpmC | QphH | FLOPS(Rmax) |
| 적합 용도 | 범용 앱 서버 CPU | OLTP DB 서버 | DW·분석 시스템 | HPC·슈퍼컴 |

> 요약: 네 벤치마크는 측정 대상·워크로드·지표·용도가 달라 선정 대상 워크로드에 맞춰 선택해야 함.

- 리스크 — 워크로드 불일치: 표준과 실업무 성격이 달라 점수 괴리 — 대응: 자사 시나리오 BMT 병행, 확인 지표 벤치마크-실측 상관도
- 리스크 — 지표 오해: Rpeak를 실성능으로 오인 — 대응: Rmax·tpmC 실측치 기준 판단, 확인 지표 이론/실측 비율
- 리스크 — 가격 무시: tpmC만 보고 $/tpmC 누락 — 대응: 가격성능 함께 평가, 확인 지표 단위당 비용

- 지표 — 연산 성능: SPECint/fp 점수 — 측정: SPEC CPU 2017 공시치
- 지표 — 트랜잭션 처리: tpmC·QphH — 측정: TPC 공인 결과
- 지표 — 부동소수점: Rmax(FLOPS) — 측정: LINPACK HPL·TOP500

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. OLTP DB 서버는 TPC-C(tpmC)·$/tpmC를, 분석·DW는 TPC-H(QphH)를 선정 기준으로 삼아 성능·비용을 함께 평가함
2. 범용 애플리케이션 서버 CPU는 SPEC CPU 2017(SPECint·SPECfp)로, HPC·시뮬레이션 클러스터는 LINPACK(Rmax·PFLOPS)으로 후보를 선별함
3. 공시 벤치마크로 초기 후보·사양(013)을 매핑한 뒤 자사 워크로드 BMT(015)로 실측 괴리를 검증하고 최종 확정함

**결론 (2줄):**
- 기술사 판단: 워크로드가 트랜잭션 중심이면 TPC 계열을, 연산·HPC 중심이면 SPEC·LINPACK을 기준으로 삼되 단일 점수 맹신을 피해야 함
- 향후 방향: AI·ML 확산으로 MLPerf 등 신규 벤치마크가 등장해 워크로드별 표준이 세분화되고 있어 다중 벤치마크 병행 평가가 확대됨
