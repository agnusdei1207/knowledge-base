# 📖 【암기용】 개념 완전 이해

> 목적: ISO/IEC 25010을 처음 봐도 왜 소프트웨어 품질을 8개 특성으로 쪼개서 보는지, 이 표준이 어디에 쓰이는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 소프트웨어 제품 품질을 기능 적합성·성능 효율성·호환성·사용성·신뢰성·보안성·유지보수성·이식성 8개 특성과 하위 특성으로 체계화한 국제 표준
- **왜 필요한가**: "품질이 좋다"는 말은 채점자도 발주기관도 검증할 수 없다. 품질을 특성별로 쪼개고 각 특성에 측정 가능한 하위 특성을 매겨야 시험·감리·계약 검수 기준으로 쓸 수 있다.
- **핵심 직관**: 종합병원 건강검진이 체중 하나로 끝나지 않고 혈압·혈당·간수치 등 항목별로 나눠 정상 범위를 판정하는 것과 같다.

## 깊이 이해
- **배경·문제의식**: 1991년 제정된 ISO/IEC 9126이 기능성·신뢰성·사용성·효율성·유지보수성·이식성 6개 특성으로 소프트웨어 품질을 규정했으나, 품질 측정 방법과 데이터 품질까지 아우르지 못했다.
- **SQuaRE 체계로 통합**: ISO/IEC 25010은 SQuaRE(Software product Quality Requirements and Evaluation) 시리즈의 핵심 표준으로, ISO/IEC 9126을 대체하며 2011년 제정됐다.
- **작동 원리**: 품질을 제품 품질 모델(8개 특성)과 사용 품질 모델(유효성·효율성·만족도·위험 회피·상황 대응)로 분리해, 개발 산출물 자체의 품질과 실제 사용 맥락에서의 품질을 별도로 평가한다.
- **8개 제품 품질 특성**: 기능 적합성(Functional Suitability), 성능 효율성(Performance Efficiency), 호환성(Compatibility), 사용성(Usability), 신뢰성(Reliability), 보안성(Security), 유지보수성(Maintainability), 이식성(Portability)이다.
- **하위 특성 구조**: 각 특성은 다시 여러 하위 특성으로 나뉘며, 예를 들어 신뢰성은 성숙성·가용성·결함허용성·복구성으로 세분화된다.
- **비유**: 8개 특성은 자동차 성능표의 연비·안전성·편의성·내구성 항목처럼 서로 다른 기준으로 나눠 채점하는 구조다.
- **2023년 개정**: ISO/IEC 25010:2023 개정판은 안전성(Safety)을 9번째 특성으로 추가해 안전 필수(Safety-critical) 시스템 평가를 명시적으로 반영했다.
- **흔한 오해·주의점**: ISO/IEC 25010을 테스트 기법 표준으로 착각하기 쉽지만, 이 표준은 품질 특성을 정의하는 모델이고 실제 측정 방법은 ISO/IEC 25023(품질 측정) 등 관련 표준이 규정한다.

## 연결 개념
- 품질 특성(기능 적합성·성능 효율성·호환성·보안성) — 25010의 하위 특성을 상세히 다루는 별도 항목
- TTA SW 품질 평가 시험 — 25010/25023 기반 국내 인증 시험 절차
- 결함 밀도·결함 제거율, 테스트 커버리지 — 품질 특성을 정량 측정하는 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: ISO 25010 답안은 9126 대체 배경, SQuaRE 체계, 8개(2023년 9개) 특성 목록, 제품 품질과 사용 품질 모델의 구분을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO/IEC 25010은 소프트웨어 품질을 8개 특성(2023년 개정 9개)과 하위 특성으로 체계화한 SQuaRE 계열 품질 모델 표준이다.
> 2. **가치**: 품질을 특성별로 쪼개 정량 측정 가능한 평가 기준을 제공해 계약 검수·감리·인증 근거로 활용한다.
> 3. **판단 포인트**: 개발 산출물 자체 평가는 제품 품질 모델, 실사용 맥락 평가는 사용 품질 모델을 적용한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 표준 체계 이해 확인 | ISO/IEC 9126 대체, SQuaRE 시리즈 위치 | 25010을 테스트 기법 표준으로 혼동 |
| 특성 구조 이해 확인 | 8개 제품 품질 특성과 하위 특성 | 특성 목록을 임의로 추가·누락 |
| 품질 모델 구분 확인 | 제품 품질 모델 vs 사용 품질 모델 | 두 모델을 동일하게 서술 |

> 요약: 이 문제는 25010의 표준 체계 위치와 8개 특성 구조를 정확히 짚어야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 소프트웨어 제품 품질을 8개 특성과 하위 특성으로 체계화한 SQuaRE 계열 국제 표준
- 배경: ISO/IEC 9126의 6개 특성 체계를 대체하며 2011년 제정, 품질 측정·요구사항 표준과 연계
- 필요성: 계약 검수·감리·인증에서 품질을 정량 판단하려면 특성별 하위 특성과 측정 지표 체계가 필요

---

## Ⅱ. 구조 및 구성요소

```text
SQuaRE 표준군
  -> 품질 요구사항(25030) -> 품질 모델(25010)
  -> 품질 측정(25023) -> 품질 평가(25040)
  -> 제품 품질 모델(8개 특성) / 사용 품질 모델(5개 특성)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 제품 품질 모델 | 개발 산출물 자체의 품질 정의 | 8개 특성(2023년 9개) |
| 사용 품질 모델 | 실사용 맥락에서의 품질 정의 | 유효성·효율성·만족도·위험회피·상황대응 |
| 하위 특성 | 각 특성을 세분화한 측정 대상 | 특성당 2~6개 하위 특성 |
| 관련 표준(25023 등) | 특성별 측정 방법·척도 정의 | 정량 지표 산출 근거 |

> 요약: ISO/IEC 25010은 SQuaRE 표준군 안에서 제품 품질과 사용 품질 모델을 정의하고 하위 표준이 측정 방법을 보완한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
평가 대상 소프트웨어 식별 -> 8개 특성별 하위 특성 매핑
  -> 25023 측정 방법 적용 -> 특성별 점수 산출
  -> 종합 품질 판정 -> 개선·인증 결정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 평가 대상과 목적(계약 검수·인증 등) 확정 | 평가 범위 명확성 |
| 2 | 8개 특성별 하위 특성을 대상 시스템에 매핑 | 특성 커버리지 |
| 3 | 관련 표준의 측정 방법으로 정량 점수 산출 | 측정 데이터 신뢰도 |
| 4 | 종합 점수로 품질 판정 및 개선 항목 도출 | 목표 기준 대비 충족 여부 |

> 요약: ISO/IEC 25010 적용은 특성 매핑 후 정량 측정을 거쳐 종합 품질을 판정하는 절차다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 품질을 8개 특성으로 분해해 정량 평가 기준 제공 | 계약·감리·인증에 표준 근거로 활용 가능 |
| 한계 | 특성 정의만으로는 측정 척도가 확정되지 않음 | 25023 등 하위 표준과 병행 적용 필요 |
| 비교 포인트 | ISO/IEC 9126의 6개 특성 대비 확장·재구성 | 보안성·호환성이 독립 특성으로 격상 |

> 요약: 25010은 품질 특성 분해에 강하지만 실제 측정은 하위 표준과 결합해야 완성된다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | ISO/IEC 9126 | ISO/IEC 25010 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 6개 특성, 품질 모델 단일 | 8개 특성, 제품/사용 품질 모델 분리 | 신규 프로젝트는 25010 적용이 표준 |
| 특성 구성 | 기능성·신뢰성·사용성·효율성·유지보수성·이식성 | 보안성·호환성 독립 특성 추가 | 보안·연동 요구가 크면 25010 필수 |
| 운영/위험 | 최신 소프트웨어 아키텍처 반영 미흡 | 하위 표준(25023 등) 병행 관리 필요 | 표준군 전체 정합성 점검 필요 |

> 요약: 최신 프로젝트는 9126 대신 25010을 적용하되 SQuaRE 하위 표준과 함께 관리한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 특성 누락 평가 | 8개 특성 중 일부만 선택 평가 | 평가 계획서에 특성 커버리지 명시 | 특성별 평가 완료 여부 |
| 측정 방법 임의화 | 하위 표준 미참조, 자체 기준 사용 | 25023 등 공인 측정 방법 적용 | 측정 방법 표준 준수 여부 |
| 인증 불일치 | 국내 인증(TTA 등)과 기준 불일치 | TTA SW 품질 평가 시험 기준과 사전 정합 | 인증 심사 결과 |

> 요약: 25010 적용 리스크는 특성 누락과 측정 방법 임의화이므로 하위 표준·국내 인증 기준과 정합해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 특성 커버리지 | 8개 특성 전체 평가 완료 | 평가 계획서·결과 보고서 |
| 측정 표준 준수 | 25023 등 공인 방법 적용률 100% | 측정 절차서 검토 |
| 인증 정합성 | 국내 인증 기준 충족 | TTA 등 인증 심사 결과 |

> 요약: 성공 여부는 특성 커버리지, 측정 표준 준수, 국내 인증 정합성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 프로젝트 착수 시 ISO/IEC 25010의 8개 특성을 요구사항 명세와 매핑함
2. 25023 등 하위 표준의 측정 방법으로 특성별 정량 점수를 산출하고 목표 기준을 설정함
3. 국내 TTA SW 품질 평가 시험 기준과 정합성을 확인해 인증·계약 검수에 활용함

**결론 (2줄):**
- 기술사 판단: 신규 프로젝트 품질 기준은 9126이 아닌 25010의 8개 특성 체계로 수립함
- 향후 방향: 2023년 개정판의 안전성(Safety) 특성을 반영해 안전 필수 시스템 평가 체계로 확장해야 함
