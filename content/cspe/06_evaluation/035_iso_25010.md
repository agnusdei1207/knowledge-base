## 미리 알고가기

- 제품 품질: 소프트웨어 자체가 갖추어야 할 품질 특성 집합임
- 사용 품질: 실제 사용 환경에서 사용자가 체감하는 품질 특성 집합임
- 비기능 요구사항: 성능, 보안, 사용성처럼 기능 외 품질 조건임
- SQuaRE: ISO/IEC 25000 계열의 소프트웨어 품질 요구와 평가 체계임

## Ⅰ. 개요

- **정의/개념**: ISO/IEC 25010은 소프트웨어 품질을 제품 품질과 사용 품질 관점으로 나누고, 평가해야 할 핵심 특성을 체계화한 국제 표준 품질 모델임
- **배경/필요성**: 버그 유무만으로는 성능, 보안, 호환성, 사용성을 설명할 수 없으므로, 요구사항 정의와 개발, 시험, 납품 검수를 같은 기준으로 연결할 품질 참조 모델이 필요함

## Ⅱ. 특징

- 품질을 추상적 인상 대신 여러 특성으로 나누어 요구사항과 시험 항목으로 연결하게 함
- 개발자, 발주자, 시험 조직이 같은 용어로 품질을 논의할 수 있게 해 줌
- 제품 자체의 구조적 품질과 실제 사용 환경에서의 체감 품질을 구분해 평가함
- 모델 자체는 평가 항목을 제시하는 기준이며, 실제 수치 측정 기준은 별도 메트릭과 시험 절차가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 제품 품질 모델 | 사용 품질 모델 |
|:---|:---|:---|
| 평가 대상 | 소프트웨어 제품 자체의 품질 특성을 봄 | 실제 사용 환경에서 사용자가 얻는 결과를 봄 |
| 대표 항목 | 기능 적합성, 성능 효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성을 포함함 | 유효성, 효율성, 만족도, 위험 회피, 상황 적합성을 포함함 |
| 활용 시점 | 요구사항 정의, 설계 기준, 시험 항목 수립에 많이 쓰임 | 실제 운영, 사용자 평가, 서비스 개선 검토에 많이 쓰임 |
| 해석 초점 | 제품이 갖춰야 할 구조적 품질 수준을 판단함 | 사용자가 목적을 달성하는 체감 품질 수준을 판단함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 품질 특성 체계 | 품질을 주 특성과 세부 특성으로 나누어 평가 기준의 누락을 줄임 |
| 비기능 요구사항 매핑 | 성능, 보안, 호환성 같은 요구를 표준 용어로 정리해 발주와 개발 기준을 맞춤 |
| 시험 및 검증 항목 | 각 특성을 시험 가능한 항목으로 내려 품질 검수와 인증 기준으로 연결함 |
| 개선 피드백 | 운영 중 발견된 품질 문제를 어떤 특성의 부족으로 볼지 분류해 개선 방향을 정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 품질 특성 정의   | --> | 요구사항 매핑   | --> | 시험 항목 도출  | --> | 결과 피드백    |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 품질 목표 선정   | --> | 특성별 요구 구체화 | --> | 시험/평가 수행  | --> | 개선 과제 반영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **품질 목표 선정**: 시스템 목적에 맞는 핵심 품질 특성을 고름
2. **특성별 요구 구체화**: 각 특성을 비기능 요구사항과 수용 기준으로 표현함
3. **시험과 평가 수행**: 정의한 기준으로 기능, 성능, 보안, 사용성을 검증함
4. **개선 과제 반영**: 미달 항목을 품질 특성 기준으로 분류해 수정 계획에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 공공 발주와 품질 검수에서는 ISO/IEC 25010 특성을 비기능 요구사항으로 풀어 써야 하지만 모든 특성을 같은 깊이로 다루면 문서만 커지므로 핵심 특성을 먼저 고르고 요구사항 반영률과 수용 기준 통과율로 확인함
2. 시험 조직과 개발 조직은 모델만 인용하고 끝내지 말고 각 특성을 실제 메트릭과 시험 절차로 연결해야 하므로 성능, 보안, 사용성 지표를 명시하고 운영 유입 결함 비율과 비기능 요구 준수율로 확인함

## Ⅶ. 결론

ISO/IEC 25010의 핵심은 품질을 많이 나누는 데 있지 않고 비기능 요구사항을 표준 특성으로 정리해 개발과 평가를 같은 기준으로 묶는 데 있음.
