# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: DR(Disaster Recovery) 사이트는 **재해복구 전략**의 핵심으로, 주 센터 재해 시 서비스를 이어받는 대체 시설이며 준비 수준에 따라 핫·웜·콜드로 등급화됨.
- **왜 필요한가**: 화재·지진·정전 같은 사이트 단위 재해는 내부 이중화(023)만으로 방어 불가. 지리적으로 분리된 대체 사이트가 있어야 사이트 전멸 시에도 서비스를 복구할 수 있음.
- **핵심 직관**: 핫 사이트 = 항상 불 켜진 예비 집(즉시 입주), 웜 사이트 = 가구는 있지만 난방 꺼둔 집(난방 켜는 시간), 콜드 사이트 = 빈 땅만 확보(집 짓는 시간).

## 핵심 용어 정리 (내부에 등장하는 것들)

023·024가 사이트 내부 HA·SPOF 제거를, 026이 RTO·RPO를 다루므로 여기서는 DR 사이트 등급 고유의 시설·복제 용어에 집중함.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| DR 사이트 (상위 키워드) | 주 센터 재해 시 서비스를 인수하는 대체 시설 | 예비 집 |
| 핫 사이트 | 주 센터와 동일 장비·실시간 복제, 즉시 전환 | 항상 불 켜진 예비 집 |
| 웜 사이트 | 핵심 장비 설치, 주기적 백업, 시간 단위 전환 | 가구 있지만 난방 꺼둔 집 |
| 콜드 사이트 | 전원·공간만 확보, 재해 후 장비·데이터 반입 | 빈 땅만 확보 |
| RTO(026) | Recovery Time Objective, 복구 목표 시간 | 정전 후 불이 다시 들어올 때까지 허용 시간 |
| RPO(026) | Recovery Point Objective, 데이터 손실 허용 시점 | 마지막 백업 이후 작성한 데이터 손실 허용 범위 |
| 재해 선언 | 공식적으로 재해 상황을 선포하고 DR 전환을 개시하는 결정 | 소방관의 대피 명령 |
| DRaaS | Disaster Recovery as a Service, 클라우드 기반 DR | 클라우드로 예비 집 빌리기 |

## 깊이 이해
- **배경·문제의식**: (023·024 참조) 사이트 내부 HA·SPOF 제거는 서버·네트워크 단위 장애를 방어하지만, 데이터센터 전체를 무력화하는 재해(화재·지진·정전·수해)에는 대응 불가. 이를 방어하려면 지리적으로 분리된 별도 시설이 필요함.
- **작동 원리 — 세 등급의 결정적 차이**:
  - **핫 사이트**: 주 센터와 동일 규모의 장비가 상시 가동, 데이터는 실시간(동기/비동기) 복제. 재해 선언 즉시 트래픽 전환 → RTO 수 분 이내. 구축·유지 비용이 가장 높음(사실상 이중 데이터센터).
  - **웜 사이트**: 핵심 장비는 사전 설치·가동하되, 데이터는 시간 단위 백업으로 유지. 재해 선언 후 최신 백업 복원·서비스 검증 → RTO 수 시간. 비용 중간.
  - **콜드 사이트**: 전원·공간·냉각 같은 기반 시설만 확보. 재해 후 장비 반입·OS 설치·데이터 복원 → RTO 수 일 이상. 비용 가장 낮음.
- **RTO·비용 반비례**: 핫→웜→콜드 순으로 RTO는 길어지고 구축·유지 비용은 낮아짐. 나인 등급(019)과 마찬가지로 등급을 한 단계 올릴 때 비용이 급증하므로, 업무 중요도에 따라 등급을 차등 적용해야 함.
- **비유**: 핫 = 항상 서 있는 택시(바로 출발, 대기 비용 비쌈), 웜 = 콜택시(부르면 5분 후 도착), 콜드 = 렌터카(예약·서류 작성·차 배정 후 출발).
- **구체 예시**: 금융 핵심 원장 → 핫 사이트(RTO 5분, RPO 0~수 초, 실시간 동기 복제). 이메일 시스템 → 웜 사이트(RTO 4h, RPO 1h, 시간 백업). 아카이브 시스템 → 콜드 사이트(RTO 3일, RPO 24h, 일간 백업).
- **흔한 오해·주의점**: ① 핫이 항상 정답이 아님 — 비핵심 업무에 핫 사이트는 과잉 투자. ② RTO만 보고 등급을 결정하면 안 됨 — RPO(026)도 함께 고려해야 데이터 손실 범위를 통제. ③ DR 사이트는 구축만으로 끝나지 않음 — 정기 DR 훈련(반기 1회 이상) 없이는 실제 전환 시 절차 미숙·데이터 불일치로 실패.

## 연결 개념
- **RTO·RPO (026)**: DR 사이트 등급을 결정하는 핵심 목표 지표. 025가 시설 등급을, 026이 시간 목표를 담당.
- **고가용성 설계 (023)**: 사이트 내부 이중화와 사이트 간 DR은 다른 계층의 방어 — 023이 내부, 025가 외부.
- **IT 서비스 연속성 관리 (059)**: DR 사이트 운영을 포괄하는 상위 관리 체계.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DR 사이트는 핫(즉시 전환, 분 단위 RTO)·웜(부분 준비, 시간 단위)·콜드(기반만, 일 단위)로 등급화됨.
> 2. **가치**: 등급 선택이 RTO 목표와 구축·유지 비용 사이의 트레이드오프를 결정함.
> 3. **판단 포인트**: 업무영향분석(BIA)으로 업무별 RTO·RPO(026)를 산정한 뒤 등급과 예산을 매칭함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 등급별 정의 이해 | 장비·데이터 준비 수준 차이 | 비용 차이만 언급하고 준비 수준 누락 |
| RTO·RPO 대응 이해 | 핫<웜<콜드 RTO 순서, RPO 연계 | RTO와 RPO 혼용 |
| 비용-등급 트레이드오프 | 핫→콜드 비용 역순, BIA 기반 매칭 | 수치 없이 "비싸다/싸다"만 서술 |

> 요약: 등급별 준비 수준·RTO 대응 + BIA 기반 등급 매칭 + 비용 트레이드오프를 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 주 센터 재해 시 서비스를 인수하는 대체 시설로, 준비 수준에 따라 핫·웜·콜드로 등급화됨
- 배경: 사이트 내부 이중화(023)만으로는 화재·지진·정전 같은 사이트 전멸 재해에 대응 불가
- 필요성: BIA로 업무별 RTO·RPO(026)를 산정하고 그에 맞는 사이트 등급과 예산을 매칭해야 재해 시 복구 가능

---

## Ⅱ. 구조 및 구성요소

```text
주 센터(Primary) -> 데이터 복제/백업 채널 -> DR 사이트(Hot/Warm/Cold)
  -> 재해 감지 -> 재해 선언 -> 사이트 활성화·트래픽 전환 -> 서비스 재개
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 주 센터 | 평상시 서비스 운영(트래픽 100%) | SPOF 제거(024) 적용 전제 |
| 복제·백업 채널 | 사이트 간 데이터 동기화 | 동기(핫)·비동기(웜)·일간 백업(콜드) |
| DR 사이트 | 재해 시 서비스 인수 시설 | 등급별 장비·데이터 준비 수준 상이 |
| 재해 선언 절차 | 전환 개시 판단·명령 체계 | RTO 카운트 시작점, 의사결정자 지정 필수 |
| 런북 | DR 전환 절차 문서 | 단계별 체크리스트·담당자·연락처 |

> 요약: 주 센터-DR 사이트 간 복제·백업 방식이 등급을 결정하고, 재해 선언 후 런북에 따라 전환을 수행함.

---

## Ⅲ. 동작원리 및 흐름도

```text
평상시 복제·백업 유지 -> 재해 발생 감지 -> 재해 선언(의사결정)
  -> DR 사이트 활성화(등급별 소요 상이) -> 트래픽 전환 -> 서비스 검증
```

1. 등급에 맞는 주기로 데이터를 복제·백업함(핫: 실시간, 웜: 시간 단위, 콜드: 일간)
2. 모니터링이 재해를 감지하면 의사결정자가 공식 재해 선언을 발동하고 RTO 카운트가 시작됨
3. DR 사이트를 등급별로 활성화함 — 핫: 즉시 트래픽 전환, 웜: 최신 백업 복원·서비스 기동, 콜드: 장비 반입·설치·데이터 복원
4. 트래픽 전환 후 서비스 정상 여부를 검증하고 실측 RTO·RPO를 목표치와 대조함

> 요약: 재해 선언 → 등급별 활성화(소요 시간 상이) → 트래픽 전환 → 검증 순으로 진행함.

---

## Ⅳ. 등급별 비교

- 핫 사이트: 장비 상시 가동 + 실시간 복제 → RTO 분 단위, RPO 수 초~0 → 비용 최고(이중 DC 운영)
- 웜 사이트: 핵심 장비 설치 + 시간 백업 → RTO 수 시간, RPO 1~수 시간 → 비용 중간
- 콜드 사이트: 기반 시설만 확보 → RTO 수 일 이상, RPO 24h → 비용 최저
- RTO-비용 반비례: 등급 한 단계 상승 시 비용 급증, 업무 중요도에 맞춘 차등 적용 필수
- DRaaS: 클라우드 기반 DR로 웜·콜드 사이트의 활성화 시간을 자동화·단축하는 대안

> 요약: 핫→웜→콜드 순으로 RTO는 길어지고 비용은 낮아지는 반비례 관계이며 BIA 기반 매칭이 핵심임.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 핫 사이트 | 웜 사이트 | 콜드 사이트 | 선택 기준 |
|:---|:---|:---|:---|:---|
| RTO | 분 단위(≤5분) | 시간 단위(≤4h) | 일 단위(1~3일) | 업무 중단 허용 시간 |
| RPO | 수 초~0 | 1~수 시간 | 24h | 데이터 손실 허용 범위 |
| 구축·유지 비용 | 최고(이중 DC) | 중간 | 최저(기반만) | 예산 대비 다운타임 손실 |
| 적합 업무 | 금융 원장·통신 | 이메일·ERP | 아카이브·개발환경 | BIA 기반 업무 중요도 |

> 요약: BIA로 업무별 RTO·RPO를 산정한 뒤 핵심 업무→핫, 중요→웜, 비핵심→콜드로 매칭함.

**리스크·대응:**
- 등급 오선택: RTO 목표 없이 비용만으로 등급 결정 → BIA 기반 RTO 산정 후 등급 매칭 (지표: 업무별 RTO 목표 문서화 여부)
- 복제 지연: 비동기 복제 lag 누적으로 RPO 초과 → 복제 지연 임계치 모니터링·알림 (지표: 복제 lag 초/분 단위)
- DR 전환 실패: 훈련 미실시로 절차 미검증·런북 미갱신 → 반기 1회 이상 DR 훈련 + 런북 갱신 (지표: 훈련 성공률, 실측 RTO)

**점검 지표:**
- 성능: DR 훈련 시 실측 RTO·RPO가 목표 이내 — 훈련 로그
- 운영: 복제 lag 모니터링 + DR 훈련 반기 1회 이상 실시 — 훈련 이력 관리대장

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. BIA로 업무별 RTO·RPO(026) 목표를 산정하고 핵심→핫, 중요→웜, 비핵심→콜드로 등급을 매칭함
2. 핫 사이트는 실시간 동기/비동기 복제를 구성하고, 웜·콜드는 백업 주기를 RPO에 맞춰 설정함
3. 반기 1회 이상 DR 전환 훈련을 실시해 실측 RTO·RPO를 목표치와 대조하고 런북을 갱신함

**결론:**
- 기술사 판단: DR 사이트 등급은 무조건 높은 것이 아니라 BIA 기반 RTO·RPO와 예산의 균형으로 결정해야 함
- 향후 방향: DRaaS(클라우드 DR)로 웜·콜드 사이트의 활성화 시간을 자동화·단축하고, 멀티 리전 Active-Active(023)로 DR과 HA의 경계가 수렴하는 추세임

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "DR 사이트를 설명하시오" | 복제·백업과 전환 구조·흐름 | 등급별 RTO·RPO·비용 비교 |
| 요구사항 명시형 | "재해복구 체계를 설계하시오" | BIA 기반 등급 매칭·전환 절차 | 리스크 대응·DR 훈련 지표 |

> 요약: 설명형은 등급별 차이 중심, 설계형은 BIA 매칭과 DR 훈련 검증을 중심으로 작성함.
