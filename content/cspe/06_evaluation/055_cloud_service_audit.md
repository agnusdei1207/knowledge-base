# 📖 【암기용】 개념 완전 이해

> 목적: 클라우드로 전환하는 공공사업을 감리할 때 무엇이 일반 SW 감리와 다른지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 클라우드 전환·구축 사업에서 서비스 모델 선택 적정성, 벤더 종속성, 보안 설정, SLA 준수를 점검하는 감리
- **왜 필요한가**: 클라우드는 자체 구축과 달리 자원을 직접 소유하지 않고 공급자 SLA와 계정 설정에 품질과 보안이 좌우되어, 일반 인프라 점검 항목만으로는 위험을 놓친다
- **핵심 직관**: 자체 서버실 감리가 건물 내부를 점검하는 것이라면, 클라우드 감리는 임대 계약 조건(SLA)과 출입 통제 설정(IAM)까지 함께 점검하는 것이다

## 깊이 이해
- **배경·문제의식**: 클라우드 전환 사업은 IaaS·PaaS·SaaS 중 서비스 모델 선택 근거가 불명확하거나, 계정 권한이 과도하게 부여되는 경우가 많아 자체 구축 감리 항목만으로는 이런 위험을 잡지 못한다
- **작동 원리**: 서비스 모델 적정성 영역은 워크로드 특성과 서비스 모델 선택 근거를 점검하고, 보안 설정 영역은 IAM 권한 최소화와 암호화 적용을 점검하며, 계약·비용 영역은 SLA 조건과 종속성 완화 방안을 점검한다
- **비유**: 서비스 모델 점검은 임대 형태(전체 임대 vs 사무실 임대) 선택이 적절한지 확인하는 것이고, 보안 설정 점검은 출입카드 권한이 직무에 맞게 부여됐는지 확인하는 것이다
- **구체 예시**: 단순 정적 콘텐츠 서비스에 고비용 관리형 데이터베이스(PaaS)를 과다 적용했다면 감리원이 서비스 모델 재검토를 요구한다
- **흔한 오해·주의점**: 클라우드로 전환했다고 보안 책임이 사라지는 것은 아니다. 클라우드 공급자는 인프라 보안을 책임지고, 이용기관은 계정 권한과 데이터 설정에 대한 책임을 진다는 책임 공유 모델을 감리에서 확인해야 한다

## 연결 개념
- CSAP 평가(056) — 클라우드 서비스 자체의 보안 인증, 서비스 감리와 점검 대상이 다름
- 지능정보기술 감리(054) — 빅데이터·AI가 결합된 사업의 클라우드 인프라 점검과 항목 일부 중복
- 벤더 종속성(lock-in) — 계약·비용 영역 점검의 핵심 리스크

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 클라우드 서비스 감리 답안은 서비스 모델 적정성, 보안 설정, SLA·종속성 점검을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 클라우드 서비스 감리는 서비스 모델 선택 적정성, 계정 보안 설정, SLA·벤더 종속성을 점검하는 감리이다.
> 2. **가치**: 책임 공유 모델에서 이용기관 책임 영역(계정 권한, 데이터 설정)의 결함을 사전에 발견한다.
> 3. **판단 포인트**: 워크로드 특성에 맞는 서비스 모델인지, IAM 권한이 최소화되었는지, SLA와 종속성 완화 방안이 있는지로 판단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 책임 공유 모델 이해 확인 | 공급자 책임(인프라)과 이용기관 책임(계정·데이터) 구분 | 클라우드 전환 후 보안 책임이 사라진다고 서술 |
| 서비스 모델 적정성 확인 | 워크로드 특성과 IaaS/PaaS/SaaS 선택 근거 | 서비스 모델 구분 없이 클라우드 도입만 서술 |
| 종속성·SLA 점검 확인 | 벤더 종속성 완화 방안, SLA 조건 검증 | 비용 절감만 언급하고 종속성 리스크 누락 |

> 요약: 이 문제는 클라우드 전환 효과보다 서비스 모델 적정성과 책임 공유 모델상 이용기관 책임 이행 여부를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 클라우드 전환·구축 사업의 서비스 모델 적정성, 보안 설정, SLA·종속성을 점검하는 감리
- 배경: 클라우드는 책임 공유 모델을 따르며 이용기관 책임 영역(계정 권한, 데이터 설정)의 결함이 자체 구축 감리 항목만으로는 확인되지 않음
- 필요성: 서비스 모델 오선정, 과도한 계정 권한, 벤더 종속성 위험을 사업 완료 이전에 확인해야 함

---

## Ⅱ. 구조 및 구성요소

```text
서비스 모델 적정성 영역 -> 보안 설정 영역 -> 계약/비용 영역
       |                       |                  |
       +-> IaaS/PaaS/SaaS 선택 +-> IAM/암호화      +-> SLA/종속성
```

| 구성요소 | 역할 | 확인 산출물 |
|:---|:---|:---|
| 서비스 모델 적정성 | 워크로드 특성 대비 서비스 모델 선택 근거 확인 | 서비스 모델 선정 보고서 |
| 보안 설정 | IAM 권한 최소화, 데이터 암호화 적용 확인 | 계정 권한 목록, 암호화 설정 내역 |
| 계약/비용 영역 | SLA 조건, 벤더 종속성 완화 방안 확인 | 계약서, 종속성 완화 계획서 |
| 재해복구 | 클라우드 리전·가용영역 이중화 확인 | DR 설계서, 복구 시험 결과 |

> 요약: 클라우드 감리는 서비스 모델-보안 설정-계약 3영역을 점검하고 재해복구 구성까지 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 특성 분석 -> 서비스 모델 선정 근거 검토 -> IAM/암호화 설정 점검
  -> SLA 조건 검증 -> 종속성 완화 방안 확인 -> DR 구성 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---|:---|:---|
| 1 | 워크로드 특성과 서비스 모델 선정 근거 대조 | 비용·운영 부담 대비 적합성 |
| 2 | 계정 권한과 데이터 암호화 설정 점검 | 최소 권한 원칙 준수 여부 |
| 3 | SLA 조건(가용성, 지원 대응시간) 검증 | 계약 SLA와 요구 수준 일치 |
| 4 | 벤더 종속성 완화 방안과 DR 구성 확인 | 이관 가능성, 리전 이중화 여부 |

> 요약: 클라우드 감리는 서비스 모델 근거 검토를 시작으로 보안 설정과 SLA·DR 구성까지 순서대로 확인한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 이용기관 책임 영역의 보안·계약 결함을 사전 발견 | 계정 권한·SLA 리스크 완화 |
| 한계 | 클라우드 공급자 내부 인프라는 이용기관 감리 범위 밖 | CSAP 등 별도 인증으로 보완 필요 |
| 비교 포인트 | 자체 구축 감리는 인프라 소유 전제, 클라우드 감리는 계약·설정 중심 | 인프라 소유 여부에 따른 점검 대상 차이 |

> 요약: 클라우드 감리는 이용기관 책임 영역을 집중 점검하되 공급자 인프라 자체는 별도 인증 체계로 보완한다.

|:---|:---|:---|:---|
| 구조 | 하드웨어·네트워크 자산 점검 중심 | 서비스 모델·계정 설정·계약 중심 | 인프라 소유 주체 |
| 비용/성능 | 사이징·용량 점검 | 서비스 모델 비용 대비 성능 적정성 | 워크로드 변동성 |
| 운영/위험 | 물리적 장애·용량 부족 위험 | 계정 오남용, 벤더 종속 위험 | 보안 통제 주체 |

> 요약: 클라우드 전환 사업은 자체 구축 점검 항목 대신 서비스 모델·계정 설정·계약 조건 중심으로 감리 범위를 재구성한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 서비스 모델 오선정 | 워크로드 특성 분석 없이 관성적 선택 | 워크로드별 비용·운영 부담 비교 분석 | 서비스 모델 재검토 건수 |
| 계정 권한 과다 부여 | 최소 권한 원칙 미적용 | 역할 기반 접근통제(RBAC) 재설계 | 과다 권한 계정 수 |
| 벤더 종속 심화 | 관리형 서비스 의존도 과다 | 표준 API·이관 가능성 사전 검토 | 이관 소요 기간 추정치 |

> 요약: 클라우드 감리 리스크는 서비스 모델 재검토, 최소 권한 재설계, 종속성 완화 계획으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 서비스 모델 적정성 | 워크로드 특성 대비 비용·운영 효율 확보 | 대안 비교 분석서 |
| 보안 설정 | 최소 권한 원칙 준수, 저장·전송 데이터 암호화 적용 | 계정 권한 감사, 암호화 설정 점검 |
| SLA·DR 준수 | 계약 SLA 가용성 목표 충족, 리전 이중화 구성 | SLA 실적 보고서, DR 시험 결과 |

> 요약: 클라우드 감리 성과는 서비스 모델 적정성, 보안 설정 수준, SLA·DR 준수 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 착수 단계에서 워크로드 특성 분석서를 근거로 서비스 모델 선정 적정성을 감리 점검 항목에 포함함
2. 중간 단계에서 IAM 최소 권한 원칙 적용과 데이터 암호화 설정을 계정 감사로 확인함
3. 완료 단계에서 SLA 조건, 벤더 종속성 완화 계획, DR 구성 시험 결과를 감리 종결 조건으로 확인함

**결론 (2줄):**
- 기술사 판단: 클라우드 감리는 책임 공유 모델을 기준으로 이용기관 책임 영역인 계정 설정과 계약 조건을 집중 점검해야 함
- 향후 방향: 멀티클라우드·하이브리드 클라우드 확산에 맞춰 종속성 완화와 이관 가능성 점검 항목을 표준화해야 함
