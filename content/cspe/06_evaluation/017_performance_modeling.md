## 미리 알고가기

- 도착률 $\lambda$: 단위 시간당 시스템에 들어오는 요청 수임
- 서비스율 $\mu$: 자원이 단위 시간당 처리할 수 있는 작업 수임
- What-if 분석: 자원 수, 부하량, 구조를 바꿨을 때 결과가 어떻게 달라지는지 미리 비교하는 방식임
- 보정(Calibration): 모델 예측값과 실측값 차이를 줄이도록 매개변수를 조정하는 과정임

## Ⅰ. 개요

- **정의/개념**: 성능 모델링은 시스템 구조와 워크로드를 수식이나 시뮬레이션 모델로 표현해 응답시간, 처리량, 자원 사용률을 실제 구축 전에 예측하는 평가 기법임
- **배경/필요성**: 시스템을 만든 뒤 성능 병목을 발견하면 구조 수정 비용이 커지므로, 설계 단계에서 예상 부하를 넣어 병목 위치와 필요한 자원 규모를 미리 판단할 기준이 필요함

## Ⅱ. 특징

- 실제 장비를 모두 준비하지 않고도 아키텍처 대안과 용량 계획을 사전에 비교함
- 분석 모델은 빠르지만 단순화 가정이 많고 시뮬레이션은 정밀하지만 구축 비용이 큼
- 모델이 아무리 정교해도 입력한 워크로드와 가정이 틀리면 결과도 쉽게 왜곡됨
- 실측 데이터와의 보정 단계를 거쳐야 설계 검토와 투자 판단에 쓸 수 있는 수준의 신뢰도를 확보함

## Ⅲ. 종류 및 비교

| 판단 기준 | 분석 모델 | 시뮬레이션 모델 |
|:---|:---|:---|
| 표현 방식 | 큐잉 이론, 리틀의 법칙 같은 수식으로 시스템을 단순화해 계산함 | 이벤트 흐름과 자원 상태 변화를 시간 순서대로 모사함 |
| 장점 | 계산 결과로 초기 설계 검토와 대안 비교를 수행함 | 복잡한 제약 조건과 비선형 거동을 더 현실적으로 반영함 |
| 한계 | 락 경쟁, 복잡한 분산 지연, 예외 흐름을 단순화해야 하는 경우가 많음 | 모델 구축과 실행 시간이 길고 입력 데이터 준비 부담이 큼 |
| 적합한 단계 | 초기 용량 산정, 병목 후보 탐색에 적합함 | 상세 설계 검증, 장애 시나리오 검토에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 워크로드 모델 | 요청 종류, 도착률, 사용자 수, 업무 비중을 정의해 무엇을 얼마나 처리할지 모델의 입력으로 만듦 |
| 자원 모델 | CPU, 메모리, 디스크, 네트워크, 동시 처리 수처럼 성능에 영향을 주는 자원 특성을 표현함 |
| 가정과 제약 조건 | 큐 길이, 병렬도, 장애율, 대기 방식처럼 현실을 어떻게 단순화했는지 명시해 결과 해석의 경계를 정함 |
| 검증 데이터 | 기존 시스템 실측값이나 소규모 시험 결과를 사용해 모델 오차를 줄이고 보정 기준을 마련함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 워크로드 정의   | --> | 자원 모델 구성  | --> | 가정/제약 반영  | --> | 예측 결과 산출  |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 목표 지표 정의  | --> | 모델 작성      | --> | 보정 및 검증    | --> | What-if 비교   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **목표 지표 정의**: 응답시간, 처리량, 자원 사용률처럼 검토할 목표를 정함
2. **모델 작성**: 워크로드와 자원 관계를 분석 모델이나 시뮬레이션 모델로 표현함
3. **보정 및 검증**: 실측 데이터와 비교해 오차를 줄이도록 매개변수를 조정함
4. **What-if 비교**: 자원 증설, 구조 변경, 부하 증가 시나리오별 결과를 비교함

## Ⅵ. 실무 적용 및 유의점

1. 신규 서비스 설계와 용량 계획에서는 분석 모델로 대안을 먼저 거르되 입력 워크로드가 실제 사용자 패턴과 다르면 결과가 흔들리므로 실측 기반 보정을 수행하고 예측 오차율과 목표 TPS 충족 여부로 확인함
2. 분산 시스템이나 대규모 트랜잭션 환경에서는 시뮬레이션 모델을 쓰되 락 경쟁과 네트워크 지연 같은 제약을 빠뜨리지 않도록 가정을 명시하고 시나리오별 응답시간과 자원 포화 지점으로 확인함

## Ⅶ. 결론

성능 모델링은 예측 자체가 목적이 아니라 워크로드와 자원 관계를 수치로 드러내어 설계안과 용량 투자안을 비교하게 하는 평가 방식임.

## 작성 근거(검토용)

- 평가·지표형 키워드이므로 분석 모델과 시뮬레이션 모델의 전제, 장점, 한계를 비교하도록 구성함
- 넓은 평가어를 줄이고 워크로드, 자원 모델, 보정, 예측 오차율로 판단 근거를 좁힘
- 절차는 목표 지표 정의에서 What-if 비교로 이어지게 배치해 설계 전 판단이라는 방향을 유지함
