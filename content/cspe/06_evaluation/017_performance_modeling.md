# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 성능 모델링(Performance Modeling)은 **시스템을 실제로 구축하기 전에 수학식(분석 모델) 또는 가상 실행(시뮬레이션)으로 응답시간·처리량·자원 이용률을 예측하는 기법**이다.
- **왜 필요한가**: 실제 부하테스트는 시스템이 완성된 뒤에만 가능하지만, 설계 단계에서 "이 구성으로 목표 TPS를 낼 수 있나"를 미리 판단해야 값비싼 재설계를 피할 수 있기 때문이다.
- **핵심 직관**: 건물을 짓기 전 구조 계산식이나 풍동 모형으로 하중·바람을 예측하듯, 시스템도 식과 모형으로 성능을 사전에 가늠한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안 Ⅰ~Ⅵ에 쓰이는 용어를 비유와 함께 먼저 못 박는다. 큐잉·λ·μ 등 기초는 005(큐잉 이론)·006(리틀의 법칙)에서 정의했으므로 여기서는 예측 도구 관점으로 연결한다. 맨 위가 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 성능 모델링 | 구축 전 성능을 식·모형으로 예측 | 시공 전 구조 계산·풍동 실험 |
| 분석 모델(Analytical) | 큐잉·수식으로 지표를 계산하는 방식 | 공식에 값 넣어 답을 즉시 계산 |
| 시뮬레이션(Simulation) | 가상 사건을 실행해 통계로 관측 | 모형 자동차를 실제로 굴려 봄 |
| 이산사건 시뮬레이션(DES) | 도착·완료를 사건 단위로 진행 | 손님 도착·처리를 하나씩 재생 |
| 큐잉 네트워크 | 여러 서비스 단계를 큐로 이은 모델 | 여러 창구가 줄줄이 이어진 공정 |
| 리틀의 법칙 L=λW | 계 내 평균 수 = 도착률×체류시간 (006 참조) | 매장 손님 수 = 입장속도×머문시간 |
| 폐쇄형 해(Closed-form) | 반복 없이 식 한 번으로 얻는 답 | 계산기 한 번에 나오는 값 |
| 워크로드 모델 | 도착 패턴·요청 구성 등 부하 가정 | 손님이 언제·무엇을 주문하나 |
| 검증(Validation) | 모델 예측을 실측과 대조해 신뢰 확인 | 예상 연비를 실주행과 비교 |

## 깊이 이해
- **배경·문제의식**: 부하테스트(009)는 실물이 있어야 하고 비용·시간이 크다. 설계 대안이 여럿일 때(서버 3대 vs 5대, 동기 vs 비동기) 모두 구축해 측정할 수는 없다. 성능 모델링은 구축 전에 대안별 성능을 예측해 후보를 좁힌다.
- **분석 모델의 원리**: 큐잉 이론(005)의 폐쇄형 산식과 리틀의 법칙(006) L=λW를 조합해, 도착률 λ·서비스율 μ·서버 수 c를 넣으면 대기시간·큐 길이·이용률이 즉시 계산된다. 여러 단계를 이으면 큐잉 네트워크가 되고, 각 노드의 지표를 합쳐 종단 응답시간을 추정한다. 장점은 빠르고 파라미터 민감도(무엇을 바꾸면 얼마나 좋아지나)를 즉시 보는 것이다.
- **시뮬레이션의 원리**: 분석 모델의 가정(포아송 도착·지수 서비스)이 깨지는 복잡한 현실(우선순위 큐, 재시도, 캐시 히트율 변동)은 수식으로 못 푼다. 이때 이산사건 시뮬레이션(DES)은 요청 도착·처리·완료를 사건으로 하나씩 실행해 통계를 관측한다 — 어떤 규칙도 코드로 표현 가능하지만, 여러 번 반복 실행해야 하고 시간이 든다.
- **비유**: 분석 모델은 "F=ma" 공식으로 즉시 답을 내는 것, 시뮬레이션은 실제로 물체를 여러 번 굴려 평균을 재는 것과 같다. 공식이 성립하는 단순한 문제는 계산이 빠르고, 공식이 없는 복잡한 문제는 굴려 봐야 한다.
- **구체 예시(워크드)**: 목표 500 TPS·평균 처리시간 40ms 서비스에서, 리틀의 법칙으로 필요한 동시 처리 수 L=λW=500×0.04=20개 스레드가 최소로 계산된다(분석 모델). 그러나 재시도·타임아웃·GC 지연이 섞이면 실제 분포가 복잡해, DES로 20·30·40 스레드 시나리오를 각 100회 돌려 p99 응답시간을 비교한다(시뮬레이션).
- **흔한 오해·주의점**: ① 모델은 가정의 산물이라 검증(Validation) 없이 신뢰하면 위험하다 — 소규모 실측과 대조해 오차를 확인해야 한다. ② 분석 모델은 M(포아송·지수) 가정이 깨지면 낙관적 편향을 보인다. ③ 시뮬레이션은 난수 기반이라 1회 결과가 아닌 다중 실행의 신뢰구간으로 판단해야 한다.

## 연결 개념
- 큐잉 이론(005) — 분석 모델의 폐쇄형 산식을 제공하는 수학적 토대
- 리틀의 법칙(006) — L=λW로 동시 처리 수·체류시간을 잇는 분석 모델 핵심 관계식
- 부하테스트·BMT(009·015) — 모델 예측을 실측으로 검증하고 파라미터를 보정하는 단계

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 성능 모델링은 구축 전에 분석 모델(수식) 또는 시뮬레이션(가상 실행)으로 응답시간·처리량·이용률을 예측하는 기법임.
> 2. **가치**: 설계 대안을 실제 구축 없이 비교해 목표 성능 달성 가능성을 사전 판단하고 재설계 비용을 절감함.
> 3. **판단 포인트**: 가정이 단순하면 빠른 분석 모델, 규칙이 복잡하면 시뮬레이션을 쓰며 실측 검증으로 신뢰를 확보함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 모델링 목적 이해 | 구축 전 지표 예측·대안 사전 비교 | 부하테스트와 동일시해 서술 |
| 두 방식 구분 | 분석 모델(폐쇄형) vs 시뮬레이션(DES) | 방식 구분 없이 모델링 일반론 |
| 신뢰성 판단 | 가정의 한계·실측 검증(Validation) | 모델 결과를 검증 없이 단정 |

> 요약: 정의보다 구축 전 예측 목적과 분석 모델·시뮬레이션 선택·검증을 보여야 함.

## Ⅰ. 개요 및 필요성

- 개요: 구축 전 시스템을 수식 또는 가상 실행으로 표현해 성능 지표를 예측하는 기법
- 배경: 부하테스트는 실물 완성 후에만 가능해 설계 대안을 사전 비교할 수단이 없음
- 필요성: 대안별 성능을 미리 예측해야 목표 미달 구성을 조기 배제하고 재설계 비용을 절감함

---

## Ⅱ. 구조 및 구성요소

- 모델링 절차(선형 구조도):

```text
워크로드 모델 정의(λ/요청 구성) -> 시스템 모델 수립(분석 모델/시뮬레이션)
  -> 파라미터 입력(μ/c/네트워크) -> 성능 지표 예측(응답시간/TPS/이용률)
  -> 실측 대조 검증 -> 대안 비교·설계 반영
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 워크로드 모델 | 도착 패턴·요청 구성 정의 | 포아송·실측 트레이스 |
| 분석 모델 | 큐잉·리틀 법칙 폐쇄형 계산 | 빠름, 가정 의존 |
| 시뮬레이션 엔진 | 이산사건 실행·통계 관측 | 복잡 규칙 표현 가능 |
| 검증 모듈 | 예측을 소규모 실측과 대조 | 오차·신뢰구간 확인 |

> 요약: 워크로드·시스템 모델을 세워 지표를 예측하고 실측 대조로 검증해 설계에 반영함.

---

## Ⅲ. 동작원리 및 흐름도

- 예측~검증 흐름(선형 흐름도):

```text
워크로드 정의 -> 모델 선택(분석/시뮬레이션) -> 파라미터 입력
  -> 지표 예측 -> 소규모 실측 대조 -> 오차 보정 -> 대안 비교
```

1. 분석자가 도착률·요청 구성 등 워크로드를 정의하고 가정의 복잡도에 따라 모델을 선택함
2. 분석 모델은 큐잉 산식·리틀 법칙에 λ·μ·c를 넣어 지표를 폐쇄형으로 즉시 계산함
3. 시뮬레이션은 도착·처리·완료를 사건 단위로 다중 실행해 응답시간 분포·p99를 관측함
4. 예측값을 소규모 실측과 대조해 오차를 보정하고 대안별 지표를 비교해 설계에 반영함

---

## Ⅳ. 특징

- 실물 구축 전 설계 단계에서 성능을 예측해 대안을 저비용으로 사전 비교함
- 분석 모델은 폐쇄형 산식으로 즉시 계산되고 파라미터 민감도를 빠르게 파악함
- 시뮬레이션은 우선순위·재시도 등 복잡 규칙을 표현하나 다중 실행 시간이 소요됨
- 모든 모델은 가정의 산물이라 실측 검증 없이는 예측 신뢰가 제한됨
- 분석 모델은 포아송·지수 가정이 깨지면 대기시간을 낙관적으로 과소추정함

---

## Ⅴ. 심화 비교 및 적용 판단

- 분석 모델 vs 시뮬레이션:

| 구분 | 분석 모델 | 시뮬레이션 |
|:---|:---|:---|
| 산출 방식 | 큐잉·리틀 법칙 폐쇄형 계산 | 이산사건 다중 실행 통계 |
| 속도 | 즉시 계산, 민감도 분석 용이 | 반복 실행으로 시간 소요 |
| 표현력 | 단순 가정(M/M/c)에 한정 | 우선순위·재시도 등 복잡 규칙 |
| 결과 형태 | 평균 지표 결정값 | 분포·p99, 신뢰구간 필요 |

> 요약: 가정이 단순하면 빠른 분석 모델, 규칙이 복잡하면 표현력 높은 시뮬레이션을 선택함.

- 리스크와 대응(불릿):
  - 검증 누락 → 모델 예측을 실측 대조 없이 신뢰 → 소규모 실측과 오차 대조 후 사용(확인: 예측·실측 오차율)
  - 가정 오류 → M 가정 깨진 부하에 분석 모델 적용 → 편차 큰 경우 시뮬레이션 전환(확인: 서비스시간 변동계수)
  - 단일 실행 판단 → 시뮬레이션 1회 결과로 결론 → 다중 실행 신뢰구간으로 판정(확인: 반복 수·구간 폭)

---

## Ⅵ. 실무 적용 및 결론

- 적용 방안:
  1. 설계 초기 리틀의 법칙(006)과 큐잉 산식으로 필요한 스레드 수·서버 대수를 폐쇄형으로 빠르게 산정함
  2. 재시도·우선순위·캐시 변동이 큰 구간은 이산사건 시뮬레이션으로 다중 시나리오의 p99를 비교함
  3. 소규모 부하테스트·BMT(009·015) 실측과 예측을 대조해 오차를 보정하고 모델을 신뢰 가능한 수준으로 검증함
- 결론:
  - 성능 모델링은 구축 전 대안을 좁히는 도구로, 단순 가정은 분석 모델·복잡 규칙은 시뮬레이션으로 나눠 적용함
  - 실측 검증과 결합한 모델을 용량 계획(058) 자동화에 연계해 예측 기반 사이징 체계로 확장 필요
