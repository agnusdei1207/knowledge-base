# 📖 【암기용】 개념 완전 이해

> 목적: 소프트웨어 신뢰도 성장 모델을 처음 봐도 테스트 중 발견되는 결함 수의 추세만으로 왜 출시 시점을 예측할 수 있는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 테스트 진행에 따라 소프트웨어 결함 발견율(고장 강도)이 감소하는 추세를 통계적으로 모델링해 잔존 결함 수와 신뢰도를 예측하는 기법
- **왜 필요한가**: "테스트를 충분히 했다"는 감각적 판단으로는 출시 시점을 결정할 수 없다. 결함 발견 추세식을 세워야 잔존 결함 수와 목표 신뢰도 도달 시점을 정량적으로 예측할 수 있다.
- **핵심 직관**: 낚시터에서 물고기를 잡을수록 남은 물고기가 줄어 잡히는 속도가 느려지는 것을 관찰해 "이 낚시터에 물고기가 몇 마리 남았는가"를 추정하는 것과 같다.

## 깊이 이해
- **배경·문제의식**: 소프트웨어는 하드웨어처럼 마모·노후화로 고장 나지 않고, 테스트 과정에서 결함을 발견해 수정할 때만 신뢰도가 개선되므로 하드웨어 신뢰성 성장 모델과 다른 별도의 통계 모델이 필요했다.
- **Jelinski-Moranda 모델**: 잔존 결함 수에 비례해 고장 강도가 일정 비율로 감소한다고 가정하는 초기 모델이며, 결함마다 동일한 발견 난이도를 전제한다.
- **Musa Basic Execution Time 모델**: 실행 시간(execution time) 단위로 결함 발견율을 측정하며, 잔존 결함 수에 비례해 고장 강도가 선형 감소한다고 가정하는 모델이다.
- **Musa-Okumoto 로그 포아송 모델(Logarithmic Poisson Execution Time Model)**: 결함마다 발견 난이도가 다르다고 가정해, 시간이 지날수록 고장 강도가 로그 형태로 서서히 감소하는 모델이다.
- **Goel-Okumoto 모델**: NHPP(Non-homogeneous Poisson Process) 기반으로 누적 결함 발견 수가 시간에 따라 지수적으로 포화(saturation)되는 곡선을 따른다고 가정하는 모델이다.
- **공통 원리**: 테스트 초기에는 결함이 자주 발견되지만 결함이 제거될수록 발견 빈도(고장 강도)가 점차 감소하며, 이 감소 추세를 곡선으로 피팅해 잔존 결함 수를 역산한다.
- **활용**: 곡선 피팅 결과로 목표 고장 강도(예: 실행시간당 결함 0.01건 이하) 도달 예상 시점을 산출해 출시 의사결정에 활용한다.
- **비유**: 곡선이 평탄해질수록(고장 강도가 낮아질수록) 낚시터에 남은 물고기가 거의 없다는 뜻이므로 낚시(테스트)를 종료해도 되는 시점에 가까워진다.
- **하드웨어 성장 모델과의 구분**: 이 모델은 소프트웨어 결함 검출·수정 이력을 다루는 Jelinski-Moranda·Musa·Goel-Okumoto 계열이며, 하드웨어 시스템의 누적 시험시간-MTBF 추세를 다루는 Duane·Crow-AMSAA 모델(별도 항목)과는 대상과 통계적 가정이 다르다.
- **흔한 오해·주의점**: 결함 발견 수가 줄었다고 해서 결함이 모두 제거됐다는 뜻은 아니다.
- **주의점 보충**: 테스트 케이스 자체가 부족하거나 특정 경로만 반복 테스트하면 발견율이 낮아 보일 뿐 잔존 결함이 그대로 남아있을 수 있다.

## 연결 개념
- 신뢰성 성장 모델(Duane·Crow-AMSAA) — 하드웨어 시스템 신뢰성 성장의 대응 개념
- 결함 밀도·결함 제거율 — 성장 모델의 입력 데이터가 되는 결함 이력 지표
- 테스트 커버리지 — 결함 발견 추세의 신뢰도를 뒷받침하는 테스트 실행 근거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SW 신뢰도 성장 모델 답안은 대표 모델(Jelinski-Moranda, Musa, Goel-Okumoto)의 가정 차이, 잔존 결함 예측 활용, 하드웨어 성장 모델과의 구분을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SW 신뢰도 성장 모델은 테스트 진행에 따른 결함 발견율 감소 추세를 통계식으로 모델링해 잔존 결함과 출시 시점을 예측하는 기법이다.
> 2. **가치**: 곡선 피팅으로 목표 고장 강도 도달 시점을 산출해 감에 의존하지 않는 정량적 출시 의사결정을 지원한다.
> 3. **판단 포인트**: 결함 발견 난이도가 균일하면 Musa Basic, 결함별 난이도가 다르면 Musa-Okumoto, 누적 결함 포화 곡선이 필요하면 Goel-Okumoto를 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SW 성장 모델 원리 이해 확인 | 결함 발견율 감소 추세, 대표 모델 이름 | 모델명 없이 "결함이 줄어든다"로만 서술 |
| 하드웨어 모델과 구분 확인 | Jelinski-Moranda/Musa/Goel-Okumoto vs Duane/Crow-AMSAA | 두 모델 계열을 혼용 |
| 출시 판단 활용 확인 | 잔존 결함 예측, 목표 고장 강도 도달 시점 | 모델 나열만 하고 출시 판단 연결 누락 |

> 요약: 이 문제는 SW 성장 모델의 통계적 가정 차이와 출시 시점 예측 활용을 함께 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 테스트 중 결함 발견율 감소 추세를 통계 모델로 피팅해 잔존 결함과 신뢰도를 예측하는 기법
- 배경: 소프트웨어는 마모성 고장이 없어 하드웨어 신뢰성 성장 모델과 다른 결함 검출 기반 모델이 필요
- 필요성: 출시 시점을 감이 아닌 잔존 결함 수·목표 고장 강도 도달 시점으로 정량 판단하기 위해 필요

---

## Ⅱ. 구조 및 구성요소

```text
테스트 실행 -> 결함 발견 기록(시간, 발생 시점)
  -> 모델 선택(Jelinski-Moranda/Musa/Musa-Okumoto/Goel-Okumoto)
  -> 곡선 피팅 -> 잔존 결함 수·목표 고장강도 도달 시점 산출
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 결함 발견 이력 | 모델 입력 데이터(발견 시각, 누적 결함 수) | 실행시간 또는 달력시간 기준 |
| Jelinski-Moranda 모델 | 결함 균일 난이도 가정 초기 모델 | 잔존 결함 비례 고장강도 감소 |
| Musa 계열 모델 | 실행시간 기반 고장강도 추세 모델 | Basic(선형), Logarithmic(로그) 구분 |
| Goel-Okumoto 모델 | NHPP 기반 누적 결함 포화 모델 | 지수적 포화 곡선 |
| 잔존 결함 예측치 | 모델 산출 결과 | 출시 의사결정 근거 |

> 요약: 결함 발견 이력을 모델에 대입해 잔존 결함 수와 목표 도달 시점을 산출하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
테스트 시작 -> 결함 발견 시각·누적 수 기록
  -> 적합 모델 선택 -> 파라미터 추정(곡선 피팅)
  -> 잔존 결함 수 산출 -> 목표 고장강도 도달 시점 계산
  -> 목표 미달 시 테스트 지속, 도달 시 출시 판단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 결함 발견 시각과 누적 발견 수를 기록 | 결함 이력 데이터 완결성 |
| 2 | 결함 발생 특성에 맞는 모델을 선택 | 모델 가정과 실제 데이터의 부합도 |
| 3 | 곡선 피팅으로 모델 파라미터를 추정 | 적합도(우도, 잔차) 검증 |
| 4 | 잔존 결함 수와 목표 도달 시점을 산출 | 목표 고장강도 대비 달성 여부 |

> 요약: 결함 이력을 모델에 피팅해 잔존 결함과 목표 도달 시점을 산출하는 절차로 진행된다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| Jelinski-Moranda | 결함 균일 난이도, 잔존 결함 비례 선형 감소 가정 | 초기 단순 모델, 실제 결함 난이도 차이 미반영 |
| Musa 계열 | 실행시간 기준 고장강도 추세, 로그형은 난이도 차이 반영 | 실행시간 데이터 확보 필요 |
| Goel-Okumoto | NHPP 기반 누적 결함 포화 곡선 | 대규모 데이터에서 안정적 적합 |

> 요약: 모델별로 결함 난이도 가정과 데이터 요구량이 달라 상황에 맞는 모델 선택이 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SW 신뢰도 성장 모델(Musa 등) | HW 신뢰성 성장 모델(Duane·Crow-AMSAA) | 선택 기준 |
|:---|:---|:---|:---|
| 대상 | 소프트웨어 결함 검출·수정 이력 | 하드웨어 고장 발생·수리 이력 | 결함이 설계 결함인지 물리적 마모인지 |
| 고장 메커니즘 | 마모 없음, 결함 발견 시에만 개선 | 마모·열화 등 물리적 요인 포함 | 소프트웨어와 하드웨어의 고장 원인 차이 |
| 입력 데이터 | 실행시간당 결함 발견 수 | 누적 시험시간당 고장 수(MTBF) | 데이터 축이 결함 수인지 MTBF인지 |

> 요약: 결함 검출 기반 예측은 SW 성장 모델, 물리적 마모 기반 예측은 HW 성장 모델로 구분해 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 조기 출시 오판 | 테스트 케이스 편중으로 발견율이 실제보다 낮게 관측 | 테스트 커버리지 확대 후 재피팅 | 분기·MC/DC 커버리지 비율 |
| 모델 부적합 | 실제 데이터가 모델 가정과 불일치 | 여러 모델 적합도 비교 후 최적 모델 선택 | 모델별 우도·잔차 비교 |
| 잔존 결함 과소 추정 | 데이터 초기 구간만으로 모델 확정 | 충분한 결함 데이터 확보 후 파라미터 재추정 | 결함 발견 건수(표본 크기) |

> 요약: 리스크는 테스트 편중과 모델 부적합이므로 커버리지 확대와 모델 적합도 비교로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 목표 고장강도 도달 | 실행시간당 결함 발견율 목표치 이하 | 모델 피팅 결과 |
| 잔존 결함 추정치 | 목표 신뢰도 대비 허용 잔존 결함 이내 | 모델 기반 잔존 결함 산출 |
| 모델 적합도 | 우도·잔차 기준 최적 모델 선정 | 복수 모델 비교 분석 |

> 요약: 성공 여부는 목표 고장강도 도달 여부, 잔존 결함 추정치, 모델 적합도로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 테스트 진행 중 결함 발견 시각과 누적 수를 기록해 모델 입력 데이터를 축적함
2. 결함 난이도 균일 여부에 따라 Musa Basic, Musa-Okumoto, Goel-Okumoto 중 적합 모델을 선택해 피팅함
3. 목표 고장강도 도달 시점과 잔존 결함 추정치를 출시 게이트 기준으로 명시함

**결론 (2줄):**
- 기술사 판단: 출시 판단은 결함 발견 추세 모델의 잔존 결함 예측치와 목표 고장강도 도달 여부로 결정함
- 향후 방향: SW 성장 모델을 결함 밀도·테스트 커버리지 지표와 연계해 CI/CD 품질 게이트로 자동화해야 함
