# 📖 【암기용】 개념 완전 이해

> 목적: 일반 SW 감리와 무엇이 다른지, AI 개발 사업 감리에서 왜 데이터와 모델을 별도로 점검하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 일반 SW 감리 점검 항목에 데이터 품질, 학습 데이터 권리관계, 모델 성능·재현성, 편향·설명가능성 점검을 추가하는 감리 방식
- **왜 필요한가**: 일반 SW는 코드가 요구사항을 구현하면 결함이 확정되지만, AI 모델은 학습 데이터와 확률적 출력에 품질이 좌우되어 코드 리뷰만으로는 결함을 잡을 수 없다
- **핵심 직관**: 일반 SW 감리가 설계도와 완성품을 비교하는 것이라면, AI 감리는 재료(데이터)의 품질과 완성품의 통계적 특성(정확도, 편향)까지 함께 검사하는 것이다

## 깊이 이해
- **배경·문제의식**: AI 모델은 동일 입력이라도 학습 데이터·하이퍼파라미터·랜덤 시드에 따라 성능이 달라져 일반 기능 테스트만으로는 품질을 보증하기 어렵다
- **작동 원리**: 데이터 영역은 라벨링 정확도와 데이터 편향을, 모델 영역은 목표 성능지표 달성 여부와 재현 가능성을, 운영 영역은 배포 후 모델 드리프트 모니터링 체계를 점검한다
- **비유**: 일반 SW 감리가 "설계대로 만들었는가"를 보는 것이라면, AI 감리는 "학습 재료가 편향되지 않았는가"와 "결과가 재현되는가"를 함께 본다
- **구체 예시**: 이미지 분류 모델 사업에서 검증 데이터셋의 클래스 비율이 학습 데이터와 크게 다르면 감리원이 데이터 분할 적정성을 지적한다
- **흔한 오해·주의점**: 정확도 수치가 목표치를 넘었다고 감리를 통과하는 것은 아니다. 학습·검증·시험 데이터셋 분리가 안 되어 있으면 그 수치 자체가 신뢰할 수 없다

## 연결 개념
- 감리 점검 항목(052) — 일반 영역 위에 AI 특수 항목을 추가하는 구조
- 지능정보기술 감리(054) — 빅데이터·클라우드까지 포함하는 상위 범주
- 결함 밀도·테스트 커버리지 — 일반 SW 품질 지표와 AI 모델 성능지표의 차이 비교 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: AI 감리 답안은 일반 SW 점검과의 차이, 데이터·모델·운영 3영역 점검, 재현성 확보 방안을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI 개발 사업 감리는 일반 SW 점검 항목에 데이터·모델·운영 특수 항목을 추가한 감리이다.
> 2. **가치**: 데이터 편향과 모델 성능 불확실성을 사업 완료 이전에 발견해 서비스 품질 저하를 예방한다.
> 3. **판단 포인트**: 목표 성능지표 달성 여부만이 아니라 데이터셋 분리, 재현성, 드리프트 모니터링 체계까지 확인한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 일반 SW 감리와 차이 이해 확인 | 데이터·모델·운영 특수 점검 항목 | AI 감리를 일반 SW 감리와 동일하게 서술 |
| 데이터 품질 점검 역량 확인 | 라벨링 정확도, 데이터 편향, 데이터셋 분리 | 정확도 수치만 언급하고 데이터 검증 누락 |
| 운영 단계 점검 이해 확인 | 모델 드리프트 모니터링, 재학습 절차 | 배포 후 점검 없이 개발 단계로 한정 |

> 요약: 이 문제는 AI 모델 성능 수치보다 데이터·모델·운영 특수 점검 구조와 재현성 확보 방안을 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 일반 SW 감리 항목에 데이터·모델·운영 특수 점검을 더한 AI 개발 사업 감리
- 배경: 확률적 출력과 데이터 의존성 때문에 코드 리뷰만으로는 AI 모델 품질을 보증하기 어려움
- 필요성: 데이터 편향, 재현 불가능한 성능 수치, 배포 후 성능 저하를 사업 완료 이전에 확인해야 함

---

## Ⅱ. 구조 및 구성요소

```text
데이터 영역 -> 모델 영역 -> 운영 영역
  |              |             |
  +-> 라벨링/편향 +-> 성능/재현성 +-> 드리프트 모니터링
```

| 구성요소 | 역할 | 확인 산출물 |
|:---|:---|:---|
| 데이터 영역 | 라벨링 정확도, 데이터 편향, 데이터셋 분리 확인 | 데이터 품질 보고서, 데이터셋 명세 |
| 모델 영역 | 목표 성능지표 달성, 재현성 확인 | 모델 평가 결과서, 실험 로그 |
| 운영 영역 | 배포 후 드리프트 모니터링 체계 확인 | 모니터링 대시보드, 재학습 절차서 |
| 윤리/설명가능성 | 편향 완화, 결과 설명 가능성 확인 | 모델 카드, 편향 점검 결과 |

> 요약: AI 감리는 데이터-모델-운영 3영역을 순서대로 점검하고 윤리·설명가능성 항목을 함께 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터셋 검증 -> 학습/검증/시험 분리 확인 -> 모델 성능 재현 시험
  -> 편향/설명가능성 점검 -> 배포 후 모니터링 체계 확인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---|:---|:---|
| 1 | 데이터셋 라벨링 정확도와 편향 점검 | 라벨 오류율, 클래스 비율 편차 |
| 2 | 학습·검증·시험 데이터 분리 여부 확인 | 데이터 누수(leakage) 여부 |
| 3 | 목표 성능지표를 동일 조건에서 재현 시험 | 정확도·F1 재현 오차 범위 |
| 4 | 배포 후 성능 저하 감지 체계 확인 | 드리프트 감지 주기, 재학습 트리거 |

> 요약: AI 감리는 데이터 검증과 데이터 분리를 먼저 확인한 뒤 성능 재현과 운영 모니터링 체계까지 점검한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 데이터 편향과 성능 재현성 문제를 배포 이전에 발견 | 서비스 품질 저하 예방 |
| 한계 | 성능지표 목표 달성 여부만으로는 실제 편향·강건성 확인이 부족 | 별도 편향·강건성 시험 필요 |
| 비교 포인트 | 일반 SW 감리는 코드·요구사항 정합성 중심, AI 감리는 데이터·모델 특성 중심 | 점검 대상의 확률적 특성 차이 |

> 요약: AI 감리는 데이터·재현성 점검으로 일반 SW 감리의 사각지대를 보완하지만 편향·강건성은 별도 시험이 필요하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 일반 SW 감리 | AI 개발 사업 감리 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 요구사항-설계-구현 정합성 중심 | 데이터-모델-운영 3영역 추가 | 사업 산출물에 학습 모델 포함 여부 |
| 비용/성능 | 코드 품질·테스트 커버리지 기준 | 데이터셋 분리, 성능 재현 오차 기준 | 모델 성능 목표치와 허용 오차 |
| 운영/위험 | 요구사항 누락 위험 | 데이터 편향, 드리프트로 인한 성능 저하 위험 | 운영 중 재학습 필요 빈도 |

> 요약: 학습 모델이 포함된 사업은 일반 점검에 데이터·모델·운영 특수 항목을 추가해 감리 범위를 확장해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 수치 신뢰 불가 | 학습·시험 데이터셋 미분리 | 데이터 분리 절차 사전 점검 | 데이터 누수 여부 |
| 데이터 편향 잔존 | 특정 클래스·집단 데이터 부족 | 클래스별 데이터 분포 점검, 증강 적용 | 클래스 분포 편차율 |
| 운영 중 성능 저하 | 실환경 데이터 분포 변화 미감지 | 드리프트 모니터링, 재학습 주기 설정 | 성능 저하 감지까지 소요 시간 |

> 요약: AI 감리 리스크는 데이터 분리 검증, 편향 점검, 운영 중 모니터링 체계로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 품질 | 라벨 오류율 목표치 이하 | 표본 재검수 |
| 모델 성능 재현성 | 재현 시험 결과와 보고 수치 오차 허용 범위 이내 | 독립 재현 시험 |
| 운영 모니터링 | 성능 저하 감지 후 재학습 트리거 정상 동작 | 모니터링 로그, 알림 이력 |

> 요약: AI 감리 성과는 데이터 품질, 성능 재현성, 운영 모니터링 정상 동작 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 착수 단계에서 데이터셋 분리 절차와 라벨링 품질 기준을 감리 점검 항목으로 사전 확정함
2. 중간·완료 단계에서 목표 성능지표를 독립 환경에서 재현 시험하고 오차 범위를 검증함
3. 이행 단계에서 배포 후 드리프트 모니터링과 재학습 트리거 절차를 감리 종결 조건으로 확인함

**결론 (2줄):**
- 기술사 판단: AI 사업 감리는 일반 SW 점검 위에 데이터·모델·운영 특수 항목을 더한 확장형 감리로 설계해야 함
- 향후 방향: 생성형 AI 사업 확대에 맞춰 환각(hallucination) 평가, 프롬프트 검증 항목을 감리 기준에 추가 검토해야 함
