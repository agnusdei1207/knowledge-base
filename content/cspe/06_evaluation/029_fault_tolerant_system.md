# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 결함 허용 시스템(Fault-Tolerant System)은 **시스템 신뢰성 설계** 기법으로, 구성요소 일부에 결함이 발생해도 **서비스 중단 없이(무중단)** 정상 기능을 유지하는 시스템임.
- **왜 필요한가**: 모든 하드웨어·소프트웨어는 확률적으로 결함이 발생함. 결함 자체를 0으로 만들 수 없으므로, 결함이 나도 서비스에 영향이 없게 **견디는(tolerant)** 구조가 필요.
- **핵심 직관**: 비행기 엔진 4개 중 1개가 꺼져도 나머지 3개로 비행을 지속할 수 있게 설계하는 것.

## 핵심 용어 정리 (내부에 등장하는 것들)

023이 HA 이중화 구조(AA/AS)를, 030이 N+1·2N 용량 모델을 다뤘으므로 여기서는 결함 허용 고유의 중복·표결 용어에 집중함.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 결함 허용 (상위 키워드) | 결함 발생 시에도 무중단으로 정상 기능을 유지하는 설계 | 엔진 1개 꺼져도 비행 지속 |
| TMR | Triple Modular Redundancy, 동일 연산을 3개 모듈이 수행하고 2-out-of-3 다수결로 채택 | 3명 심판 중 2명 일치 판정 |
| DMR | Dual Modular Redundancy, 2중 모듈 + 비교기 | 2명 심판 + 주심 판정 |
| 표결기(Voter) | 중복 유닛 결과를 비교해 다수결 채택하는 장치 | 심판 판정석 |
| ECC | Error Correcting Code, 데이터 비트 오류를 자동 검출·정정 | 오류 교정 코드 |
| 워치독 타이머 | 응답 없는 유닛을 timeout 기반으로 감지·격리 | 무응답 시 경보기 |
| 마스킹 | 결함의 영향이 출력에 나타나지 않게 숨기는 것 | 결함을 덮어쓰기 |

## 깊이 이해
- **배경·문제의식**: 결함 방지(fault avoidance)는 품질·테스트로 MTBF(018)를 높이는 접근이지만, MTBF는 유한이므로 결함은 반드시 발생함. HA(023)는 장애 감지 후 페일오버(028)로 짧은 중단 후 복구하는 구조인 반면, 결함 허용은 그보다 세밀하게 **연산·컴포넌트 단위**에서 결함을 즉시 마스킹해 중단 자체를 없앰.
- **작동 원리 — TMR(Triple Modular Redundancy)**:
  - 동일 입력을 3개 독립 모듈에 동시 전달 → 각 모듈이 독립적으로 연산 수행.
  - 표결기(Voter)가 3개 출력을 비교 → 2개 이상 일치하는 결과를 다수결(2-out-of-3)로 채택.
  - 불일치 모듈을 결함으로 식별해 격리 → 출력은 끊기지 않음(마스킹).
  - 1개 모듈 결함을 허용하므로 단일 결함 허용(single fault tolerance)을 보장.
- **그 외 메커니즘**: ECC(메모리 비트 오류 정정), 체크섬/CRC(데이터 전송 오류 검출), 워치독 타이머(무응답 유닛 격리), 중복 디스크(RAID).
- **HA와의 결정적 차이**: HA는 "장애 → 감지 → 전환(페일오버)" 과정에서 초~분 단위 순단이 발생함. 결함 허용은 "결함 → 마스킹"으로 순단 자체가 0임. 대신 비용이 2~3배 이상(중복 하드웨어·전력).
- **비유**: HA = 교대 근무(한 명 빠지면 다음 사람 투입, 교대 시간 존재). 결함 허용 = 동시 근무(3명이 동시에 같은 일을 하고, 결과가 다른 1명만 배제, 업무 공백 0).
- **구체 예시**: 항공기 비행제어 컴퓨터(FCC)는 TMR 또는 4중화 구성. 1개 모듈 결함 시 나머지 2~3개의 다수결로 정상 출력 유지. 금융 결제 스위치도 TMR 기반 무중단 처리 적용.
- **흔한 오해·주의점**: ① 결함 허용 ≠ HA. HA는 순단을 감수한 전환, 결함 허용은 순단 0. ② 모든 시스템에 적용하면 비용이 2~3배 → 항공기·원자력·금융 결제처럼 무중단이 절대적인 영역에 선별 적용. ③ 표결기 자체가 SPOF(024)가 될 수 있어 표결기도 이중화 필요.

## 연결 개념
- **고가용성 설계 (023)**: 노드 단위 이중화(AA/AS)와 결함 허용의 세밀도 차이. 023이 노드 전환, 029가 연산 마스킹.
- **FMEA (034)**: 결함 허용 설계 전 결함 유형·영향을 식별하는 분석 기법.
- **이중화 구성 N+1·2N (030)**: 결함 허용을 용량 관점에서 구현하는 중복성 설계 모델.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 결함 허용 시스템은 중복 연산 + 표결로 결함을 마스킹해 서비스 중단 자체를 없애는 설계임.
> 2. **가치**: HA의 순단(초~분)조차 허용 불가한 영역(항공·원자력·금융 결제)에 무중단을 보장함.
> 3. **판단 포인트**: HA로 충분한 영역에 결함 허용을 적용하면 2~3배 과잉 투자 → 무중단 필수 영역에만 선별 적용함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정의 이해 | 결함 발생 ≠ 서비스 중단(마스킹) | HA와 동일 개념으로 서술 |
| 메커니즘 이해 | TMR·표결(Voting)·ECC 구체 제시 | 메커니즘 없이 "이중화"만 서술 |
| 적용 판단 | 비용 2~3배, 무중단 필수 영역 선별 | 모든 시스템에 적용 가능하다고 단정 |

> 요약: HA와의 차이(순단 vs 무중단) + 표결 메커니즘 + 선별 적용 판단을 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 결함 발생 시에도 중단 없이 정상 기능을 유지하는 시스템(중복 연산 + 표결 기반 마스킹)
- 배경: 결함 방지(fault avoidance)만으로는 MTBF(018)가 유한하므로 한계, 결함 발생을 전제로 한 설계 필요
- 필요성: 항공·원자력·금융 결제처럼 순간 중단도 허용 불가한 영역은 TMR 기반 무중단 마스킹이 필수

---

## Ⅱ. 구조 및 구성요소

```text
동일 입력 -> 중복 유닛(A, B, C) 병렬 연산
  -> 표결기(Voter): 결과 비교, 다수결(2-out-of-3) 채택
  -> 불일치 유닛 격리 -> 무중단 출력 유지
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 중복 유닛 | 동일 연산을 독립적으로 병렬 수행 | DMR(2중), TMR(3중) |
| 표결기(Voter) | 다수결 결과 채택, 불일치 유닛 식별 | 2-out-of-3, 자체 이중화 필요 |
| ECC/체크섬 | 데이터 비트 오류 검출·정정 | 메모리·전송 계층 보호 |
| 워치독 타이머 | 무응답 유닛 timeout 감지·격리 | 무한 루프·행 감지 |

> 요약: 중복 유닛이 병렬 연산 → 표결기가 다수결 채택 → 결함 유닛 격리 → 무중단 출력 유지하는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
입력 동기 전달(3유닛) -> 독립 병렬 연산 -> 표결기 결과 비교
  -> 2개 이상 일치: 다수결 채택, 불일치 유닛 격리 -> 무중단 출력
  -> 전 유닛 불일치: 안전 모드 전환(fail-safe)
```

1. 동일 입력을 3개 독립 유닛에 동기 전달하고 각 유닛이 독립적으로 연산을 수행함
2. 표결기(Voter)가 3개 출력을 비교해 2개 이상 일치하는 결과를 다수결(2-out-of-3)로 채택함
3. 불일치 유닛을 결함으로 식별해 격리(오프라인 전환)하고, 출력은 끊기지 않음(마스킹)
4. 격리된 유닛을 수리·교체 후 재투입하거나, 전 유닛 불일치 시 안전 모드(fail-safe)로 전환함

> 요약: 병렬 연산 → 표결 → 결함 유닛 격리 → 무중단 출력 순으로 결함을 실시간 마스킹함.

---

## Ⅳ. 특징

- 무중단 마스킹: HA(023)의 페일오버는 초~분 순단이 발생하나, 결함 허용은 표결로 순단 자체가 0
- 연산 단위 세밀도: HA가 노드·서버 단위 전환이라면, 결함 허용은 연산·컴포넌트 단위 중복
- 비용 배수: 2중(DMR)~3중(TMR) 중복으로 하드웨어·전력 비용이 2~3배 이상 증가
- 표결기 SPOF 위험: 표결기 자체가 단일 구성이면 새로운 SPOF(024) → 표결기도 이중화 필수
- 선별 적용: 항공기 FCC·원자력 제어·금융 결제 등 무중단 필수 영역에만 적용, 나머지는 HA(023)가 비용 효율적

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 고가용성(HA, 023) | 결함 허용(Fault-Tolerant) | 선택 기준 |
|:---|:---|:---|:---|
| 결함 대응 | 감지→페일오버(028) 전환 | 중복 연산→표결→마스킹 | 순간 중단 허용 여부 |
| 서비스 영향 | 페일오버 소요만큼 순단(초~분) | 이론상 중단 0 | RTO 초단위 vs 0 |
| 구현 단위 | 노드·서버 단위 이중화 | 연산·컴포넌트 단위 중복(TMR) | 세밀도 요구 수준 |
| 비용 | 이중화 수준(N+1, 030) | 2~3배 중복(하드웨어·전력) | 무중단 요구 vs 예산 |

> 요약: 순간 중단도 허용 안 되는 영역만 결함 허용, 나머지는 비용 효율적인 HA(023)를 적용함.

**리스크·대응:**
- 표결기 SPOF: 표결기(Voter) 자체가 단일 구성 → 표결기도 이중화 또는 분산 구성 (지표: 표결기 장애 이력 0건)
- 과잉 적용: 무중단 필수 아닌 영역에 TMR 적용 → BIA 기반 업무 중요도 분석 후 선별 (지표: 결함 허용 적용 영역 대비 무중단 필수 비율)
- 입력 동기화 오류: 중복 유닛 간 입력 타이밍 불일치 → 입력 동기화 프로토콜 검증 + 결함 주입 테스트 (지표: 유닛 간 입력 불일치 건수)

**점검 지표:**
- 성능: 결함 주입 테스트 시 서비스 중단 0초 — 결함 주입 시나리오 로그
- 운영: 표결 정확도(다수결 오판정 0건) + 결함 감지율 100% — 표결기 로그·감사

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. BIA로 무중단이 절대적으로 요구되는 업무(결제 승인·항공 제어·원자력)를 식별해 TMR 기반 결함 허용을 선별 적용함
2. 표결기 자체도 이중화해 표결기가 SPOF(024)가 되지 않도록 구성하고, 입력 동기화 프로토콜을 검증함
3. 정기 결함 주입 테스트로 서비스 중단 0초 목표와 결함 감지율 100%를 검증함

**결론:**
- 기술사 판단: 결함 허용은 HA(023)보다 비용이 2~3배이므로 무중단 필수 영역에만 선별 적용하고, 나머지는 HA로 충분함
- 향후 방향: SW 정의 이중화(Kubernetes self-healing)와 컨테이너 수준 결함 허용 패턴으로 적용 영역이 확대되는 추세임
