## 미리 알고가기

- Bandwidth: 링크나 장치가 이론적으로 전송할 수 있는 최대 용량임
- Throughput: 실제 환경에서 단위 시간 동안 성공적으로 처리된 데이터량임
- Goodput: 헤더, 재전송, 제어 트래픽을 뺀 애플리케이션 유효 데이터 처리량임
- BDP: 대역폭과 왕복 지연시간을 곱한 값으로 네트워크 파이프를 채우는 데 필요한 데이터량임

## Ⅰ. 개요

- **정의/개념**: 처리율과 대역폭은 이론적 전송 가능량과 실제 성공 처리량을 구분해 네트워크와 시스템 용량을 판단하는 성능 지표임
- **배경/필요성**: 장비 사양의 대역폭만으로 용량을 산정하면 프로토콜 오버헤드, 손실, 혼잡 제어 때문에 실제 처리량 부족을 놓칠 수 있음

## Ⅱ. 특징

- 대역폭은 물리 링크나 버스의 상한이며 운영 조건에 따라 즉시 달라지는 실측값이 아님
- 처리율은 손실, 재전송, 혼잡 제어, 서버 처리 능력의 영향을 받는 실측값임
- Goodput은 사용자가 실제로 받은 유효 데이터량을 보여 주므로 업무 기준 용량 산정에 적합함
- 장거리 네트워크에서는 대역폭보다 RTT와 윈도우 크기가 처리율을 제한함

## Ⅲ. 종류 및 비교

| 판단 기준 | 대역폭 | 처리율 | Goodput |
|:---|:---|:---|:---|
| 의미 | 이론적 최대 전송 용량임 | 실제 성공 처리량임 | 애플리케이션 유효 처리량임 |
| 측정 위치 | 링크, NIC, 스토리지 버스 사양에서 확인함 | 네트워크·시스템 테스트로 측정함 | 업무 데이터 기준으로 측정함 |
| 감소 요인 | 물리 매체와 장비 한계가 좌우함 | 손실, 혼잡, 재전송, 서버 병목이 줄임 | 헤더, 제어 패킷, 재전송을 제외함 |
| 활용 | 인프라 상한 확인에 사용함 | 성능 시험과 용량 산정에 사용함 | 사용자 체감 전송량 판단에 사용함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 물리·논리 링크 | 회선 속도, NIC, 스위치, 버스 대역폭으로 전송 상한을 정함 |
| 프로토콜 오버헤드 | TCP/IP, TLS, Ethernet 헤더와 제어 트래픽이 유효 전송량을 줄임 |
| 손실·재전송 | 패킷 손실과 재전송이 같은 대역폭 안에서 처리율을 낮춤 |
| 수신 처리 능력 | 서버 CPU, 디스크, 애플리케이션 처리 속도가 네트워크 밖 병목을 만들 수 있음 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| Bandwidth  | --> | Throughput | --> | Goodput    | --> | 업무 처리량 |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 사양 확인    | --> | 실측 수행    | --> | 오버헤드 분리 | --> | 용량 판정    |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **사양 확인**: 회선, NIC, 스토리지의 이론적 대역폭을 확인함
2. **실측 수행**: 실제 업무 또는 표준 부하로 처리율을 측정함
3. **오버헤드 분리**: 헤더, 재전송, 제어 트래픽을 제외해 Goodput을 계산함
4. **용량 판정**: 목표 처리량과 비교해 링크 증설 또는 병목 제거를 결정함

## Ⅵ. 실무 적용 및 유의점

1. 회선 증설 검토에서는 대역폭 부족인지 손실·RTT 문제인지 먼저 나누어야 하므로 link utilization, retransmission rate, p95 RTT를 함께 확인함
2. 파일 전송과 백업 시스템에서는 처리율보다 Goodput이 업무 완료 시간을 설명하므로 payload bytes/sec와 재전송률로 개선 여부를 확인함

## Ⅶ. 결론

처리율과 대역폭의 판단은 큰 회선을 고르는 문제가 아니라 이론 상한, 실제 성공량, 유효 업무량을 분리해 병목 위치를 찾는 일임.

## 작성 근거(검토용)

- 대역폭과 처리율은 자주 혼동되므로 정의보다 측정 위치와 감소 요인을 비교축으로 잡음
- 비유적 평가어를 제거하고 링크 상한, 손실, 재전송, Goodput으로 구체화함
- 실무 유의점은 회선 증설과 업무 전송량 판단으로 제한해 주제 이탈을 줄임
