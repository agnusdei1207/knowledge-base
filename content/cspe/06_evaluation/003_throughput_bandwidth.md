# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **처리율(Throughput)**(001 성능지표의 처리량 참조)은 실제 조건에서 달성한 전송·처리량이고, **대역폭(Bandwidth)** 은 매체가 낼 수 있는 이론적 최대 전송 용량으로, 둘의 격차와 그 원인을 다루는 관점이다.
- **왜 필요한가**: 회선 사양(대역폭)만 보고 실서비스 성능을 예단하면 프로토콜 오버헤드·혼잡·재전송을 반영하지 못해 용량 산정이 틀어지기 때문이다.
- **핵심 직관**: 4차선 도로의 이론적 최대 통행량(대역폭)과, 신호·사고로 줄어든 실제 통행량(처리율)의 차이와 같다 — 규격은 상한일 뿐 보장치가 아니다.

## 핵심 용어 정리

처리량의 전체 정의는 001에 있으므로, 여기서는 이론 상한(대역폭)과 실측치(처리율)의 계층과 격차 요인에 집중한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 대역폭(Bandwidth) | 매체·인터페이스가 지원하는 이론적 최대 전송 용량(bps) | 수도관의 규격상 최대 유량 |
| 처리율(Throughput) | 일정 시간 실제로 전달·처리된 양을 시간으로 나눈 값 (001 참조) | 실제로 흘러나온 물의 양 |
| Goodput(유효 처리율) | 재전송·오류·헤더를 뺀 순수 유효 데이터의 처리율 | 오염·누수를 뺀 마실 수 있는 물의 양 |
| 프로토콜 오버헤드 | 헤더·제어 정보 등 실 데이터가 아닌 전송 비용 | 택배 상자·포장재의 무게 |
| 혼잡 제어(Congestion Control) | 링크 혼잡 시 전송률을 낮춰 붕괴를 막는 TCP 메커니즘 | 막히면 속도를 줄이는 운전 |
| 재전송(Retransmission) | 손실·오류 패킷을 다시 보내는 것(처리율을 깎음) | 잘못 배달돼 다시 보내는 택배 |
| RTT (Round Trip Time) | 요청~응답 왕복 지연시간 | 편지를 보내고 답장받기까지 |
| bps / Mbps / Gbps | 초당 비트 수 단위(전송 속도의 단위) | 1초에 흐르는 물방울 개수 |

## 깊이 이해
- **배경·문제의식**: 네트워크·시스템 사양서에는 대역폭(예: 1Gbps)만 표기되지만, 실서비스는 헤더 오버헤드·혼잡 제어·재전송 탓에 그보다 낮은 처리율을 낸다. 그래서 상한과 실측을 반드시 나눠 본다.
- **작동 원리 — 계층 관계**: Goodput ≤ Throughput ≤ Bandwidth. 대역폭은 물리 매체가 정한 상한, 처리율은 그 안에서 오버헤드·혼잡을 뺀 실측, Goodput은 다시 재전송·오류·헤더까지 뺀 순수 유효량이다. 아래로 갈수록 값이 좁혀진다.
- **왜 처리율이 대역폭에 못 미치나**: ① 헤더 오버헤드(TCP/IP 헤더가 매 패킷 붙음) ② 혼잡 제어(윈도가 커지기 전엔 링크를 못 채움) ③ 재전송(손실분을 다시 보내 유효량 감소) ④ RTT가 클수록 확인응답 대기가 늘어 링크가 비는 시간이 생김.
- **비유**: 수도관의 규격 유량(대역폭)과, 밸브·수압·누수로 실제 흘러나온 물의 양(처리율), 그중 마실 수 있는 깨끗한 물(Goodput)의 관계와 같다.
- **구체 예시**: 1Gbps 회선에서 TCP 오버헤드·혼잡 제어·재전송을 감안하면 실측 처리율이 약 850Mbps로 나오고, 헤더·재전송분을 뺀 Goodput은 그보다 더 낮다. 즉 "1Gbps 회선이니 1Gbps가 나온다"는 가정은 용량 과다 산정으로 이어진다.
- **흔한 오해·주의점**: 대역폭 수치는 상한선일 뿐 보장치가 아니다. 또 처리율이 대역폭에 근접했다고 응답시간이 짧다는 뜻은 아니다 — 응답시간(지연)은 별개 축(001·002)이며, 링크가 꽉 찰수록 오히려 큐 대기로 지연이 늘 수 있다(throughput↔latency 혼동 금지).

## 연결 개념
- 시스템 성능 지표(001) — 처리량의 상위 정의와 다른 축(TPS·응답시간)
- 응답 시간 분해(002) — 처리율이 높아도 대기로 지연이 늘 수 있는 이유
- 병목 분석·큐잉 이론 — 처리율이 대역폭·도착률을 못 따라갈 때 대기가 생기는 근거

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 대역폭은 이론적 최대 전송 용량(bps), 처리율은 실제 조건에서 측정된 전송·처리량임.
> 2. **가치**: 둘을 구분해야 회선·시스템 사양만으로 실서비스 용량을 오판하지 않음.
> 3. **판단 포인트**: Goodput ≤ Throughput ≤ Bandwidth 순으로, 격차 원인(오버헤드·혼잡·재전송)을 식별해 설계·튜닝 대상을 정함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개념 구분 역량 확인 | 대역폭(이론 상한)과 처리율(실측치)의 차이 | 두 용어를 동일 의미로 혼용 |
| 격차 원인 분석 확인 | 오버헤드·혼잡 제어·재전송·RTT | 원인 언급 없이 수치만 제시 |
| Goodput 개념 확인 | 유효 데이터 기준 Goodput ≤ Throughput | Goodput과 Throughput을 동일 개념으로 서술 |

> 요약: 수치 나열보다 대역폭·처리율·Goodput의 계층 관계와 격차 원인을 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 대역폭은 매체가 지원하는 이론적 최대 전송 용량(bps), 처리율은 실제 측정된 전송·처리량
- 배경: 처리량의 전체 정의는 상위 지표(001)에 있고, 본 키워드는 이론 상한과 실측치를 계층으로 나눠 격차를 다룸
- 필요성: 회선·서버 용량 산정 시 상한과 실측을 분리해야 과다·과소 산정을 막을 수 있음

---

## Ⅱ. 구조 및 구성요소

- 값이 좁혀지는 계층(선형 구조도):

```text
물리 매체/인터페이스 -> 대역폭(이론 상한, bps)
  -> [프로토콜 오버헤드·혼잡 제어 차감] -> 처리율(Throughput, 실측)
  -> [재전송·오류·헤더 차감] -> Goodput(유효 처리율)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 물리 매체/인터페이스 | 이론 상한 결정 | NIC 규격, 회선 등급(1G/10G) |
| 프로토콜 스택 | 헤더·제어 오버헤드 부과 | TCP/IP 헤더, 혼잡 제어 알고리즘 |
| 측정 도구 | 실제 처리율 측정 | iperf, APM, 인터페이스 카운터 |
| Goodput 산출 | 재전송·오류 제외 후 유효량 계산 | 재전송률·오류율 반영 |

> 요약: 이론 상한(대역폭)에서 오버헤드·혼잡·재전송을 차감하며 처리율, 다시 Goodput으로 좁혀짐.

---

## Ⅲ. 동작원리 및 흐름도

- 실측 산출 흐름(선형 흐름도):

```text
전송 시작 -> 매체 상한 내 전송 -> 오버헤드·혼잡 반영
  -> 손실 시 재전송 -> 일정 시간 전송량 집계 -> 처리율 -> 유효분만 재계산(Goodput)
```

1. 매체 대역폭 한도(bps) 내에서 전송을 시작함
2. 프로토콜 헤더·혼잡 제어 오버헤드가 반영돼 실효 전송이 상한보다 낮아짐
3. 일정 시간 전송량을 집계해 실측 처리율(bps·TPS)을 산출함
4. 재전송·오류 데이터를 제외해 유효 처리율(Goodput)을 계산함

---

## Ⅳ. 특징

- 대역폭은 물리 매체가 정한 고정 상한, 처리율은 조건에 따라 변하는 실측값임
- 처리율은 항상 대역폭 이하이며 오버헤드·혼잡·재전송·RTT 탓에 격차가 발생함
- Goodput은 처리율에서 헤더·재전송·오류를 뺀 순수 유효량으로 실사용 용량에 가장 근접함
- 처리율이 높아도 응답시간(지연)이 짧다는 보장은 없음 — 지연은 별개 축(001·002)임
- 처리량 단위(bps·TPS·RPS)를 명시하지 않으면 서로 다른 값이 혼동됨

---

## Ⅴ. 심화 비교 및 적용 판단

- 용량 산정 기준 — 사양치 vs 실측치:

| 구분 | 대역폭(사양서) | 처리율(실측) |
|:---|:---|:---|
| 용도 | 회선·장비 선정 시 상한 참고 | 실서비스 용량 산정 근거 |
| 성격 | 고정된 규격 상한 | 부하·혼잡에 따라 변동 |
| 리스크 | 과다 산정으로 병목 미반영 | 측정 조건 따라 값이 달라짐 |

> 요약: 회선·장비 선정은 대역폭, 서비스 용량 산정은 실측 처리율을 기준으로 삼음.

- 리스크와 대응(불릿):
  - 대역폭 과신 → 사양 수치를 실사용치로 오인 → 실측 처리율 기반 산정(확인: 실측 bps, 사양 대비 달성률)
  - 오버헤드 미반영 → 헤더·혼잡 제어 비용 간과 → 오버헤드율 사전 실측 후 여유율 반영(확인: 오버헤드율)
  - Goodput 저하 → 재전송·오류율 증가 → 회선 품질·혼잡 제어 튜닝(확인: 재전송률, 오류율)

---

## Ⅵ. 실무 적용 및 결론

- 적용 방안:
  1. 회선·장비 선정 시 사양서 대역폭과 별도로 iperf 등 실측 처리율 데이터를 확보해 산정에 반영함
  2. 부하테스트로 오버헤드·혼잡 제어 영향을 실측해 대역폭과 처리율의 격차를 문서화함
  3. Goodput 저하 시 재전송률·오류율을 모니터링해 회선 품질·혼잡 제어 파라미터를 조정함
- 결론:
  - 용량 산정은 대역폭이 아닌 실측 처리율과 Goodput을 기준으로 수행해야 함
  - 실시간 트래픽 모니터링과 오토스케일링을 연계해 처리율 저하를 사전 탐지하는 체계로 확장 필요
