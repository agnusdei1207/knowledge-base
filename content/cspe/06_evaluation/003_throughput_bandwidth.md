# 📖 【암기용】 개념 완전 이해

> 목적: 대역폭은 이론적 한계, 처리율은 실제 달성치라는 차이를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 대역폭(Bandwidth)은 링크·시스템이 낼 수 있는 이론적 최대 전송 용량, 처리율(Throughput)은 실제 조건에서 달성한 전송·처리량
- **왜 필요한가**: 회선 사양(대역폭)만 보고 실제 서비스 성능을 예단하면 오버헤드·혼잡·재전송을 반영하지 못해 용량 산정이 틀어짐
- **핵심 직관**: 왕복 4차선 도로의 이론적 최대 통행량(대역폭)과 신호 대기·사고로 줄어든 실제 통행량(처리율)의 차이와 같음

## 깊이 이해
- **배경·문제의식**: 네트워크·시스템 사양서에는 대역폭(예: 1Gbps)만 표기되지만 실제 서비스는 프로토콜 오버헤드, 혼잡 제어, 재전송으로 그보다 낮은 처리율을 냄
- **작동 원리**: 대역폭은 물리 매체·인터페이스가 지원하는 초당 최대 비트 수(bps)이며, 처리율은 일정 시간 동안 실제로 전달된 데이터량을 그 시간으로 나눈 값
- **비유**: 수도관의 최대 유량 규격(대역폭)과 실제 수압·밸브 개폐로 흘러나오는 물의 양(처리율)의 관계와 같음
- **구체 예시**: 예시로 1Gbps 회선에서 TCP 오버헤드, 혼잡 제어, 재전송을 감안하면 실제 처리율이 850Mbps 수준으로 측정되는 경우, 유효 데이터만 계산한 Goodput은 이보다 더 낮아질 수 있음
- **흔한 오해·주의점**: 대역폭 수치는 상한선일 뿐 보장치가 아니며, 처리율이 대역폭에 근접했다고 자동으로 응답시간이 짧다는 의미는 아님(대기시간은 별도 지표)

## 연결 개념
- 시스템 성능 지표(TPS·응답시간) — 처리율과 함께 보는 다른 축의 지표
- 병목 분석 — 처리율이 대역폭보다 낮아지는 원인 자원을 찾는 절차
- 큐잉 이론 — 처리율이 도착률을 못 따라갈 때 대기가 발생하는 근거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 처리율·대역폭 답안은 개념 정의 차이, Goodput≤Throughput≤Bandwidth 관계, 격차 발생 원인을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 대역폭은 이론적 최대 전송 용량(bps), 처리율은 실제 조건에서 측정된 전송·처리량이다.
> 2. **가치**: 둘을 구분해야 회선·시스템 사양만으로 실서비스 용량을 오판하지 않는다.
> 3. **판단 포인트**: Goodput ≤ Throughput ≤ Bandwidth 순서로, 격차의 원인(오버헤드·혼잡·재전송)을 식별해 설계·튜닝 대상을 정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개념 구분 역량 확인 | 대역폭(이론 상한)과 처리율(실제 달성치) 차이 | 두 용어를 동일한 의미로 혼용 |
| 격차 원인 분석 확인 | 프로토콜 오버헤드, 혼잡 제어, 재전송 | 격차 발생 원인 언급 없이 수치만 제시 |
| Goodput 개념 확인 | 유효 데이터 기준의 Goodput ≤ Throughput | Goodput과 Throughput을 동일 개념으로 서술 |

> 요약: 이 문제는 수치 나열보다 대역폭·처리율·Goodput의 계층 관계와 격차 원인을 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 대역폭은 매체가 지원하는 이론적 최대 전송 용량(bps), 처리율은 실제 측정된 전송·처리량
- 배경: Goodput(유효 데이터량) ≤ Throughput(실제 처리량) ≤ Bandwidth(이론 상한) 관계로 계층을 구분
- 필요성: 회선·서버 용량 산정 시 이론 상한과 실측치를 분리해야 과다·과소 산정을 방지할 수 있음

---

## Ⅱ. 구조 및 구성요소

```text
물리 매체/인터페이스 -> 대역폭(이론 상한, bps)
  -> 프로토콜 오버헤드/혼잡 제어 -> 실제 처리율(Throughput)
  -> 재전송/오류 데이터 제외 -> Goodput(유효 처리율)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 물리 매체/인터페이스 | 전송 가능한 이론 상한 결정 | NIC 규격, 회선 등급(1G/10G) |
| 프로토콜 스택 | 헤더·제어 오버헤드 부과 | TCP/IP 헤더, 혼잡 제어 알고리즘 |
| 측정 도구 | 실제 처리율 측정 | iperf, APM, 인터페이스 카운터 |
| Goodput 계산 | 재전송·오류 데이터 제외 후 유효량 산출 | 재전송률, 오류율 반영 |

> 요약: 이론 상한인 대역폭에서 오버헤드·혼잡·재전송을 제하며 처리율, 다시 Goodput 순으로 좁혀진다.

---

## Ⅲ. 동작원리 및 흐름도

```text
전송 시작 -> 매체 상한 내 전송 -> 프로토콜 오버헤드 반영
  -> 혼잡·오류 발생 시 재전송 -> 일정 시간 전송량 집계
  -> 처리율 산출 -> 유효 데이터만 재계산(Goodput)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 매체 대역폭 한도 내 전송 시작 | 인터페이스 규격(bps) |
| 2 | 프로토콜 헤더·혼잡 제어 오버헤드 반영 | 오버헤드 비율 |
| 3 | 일정 시간 동안 전송량 집계해 처리율 산출 | 실측 처리율(bps, TPS) |
| 4 | 재전송·오류 데이터 제외 후 Goodput 계산 | 재전송률, 유효 처리율 |

> 요약: 대역폭 한도 내에서 오버헤드와 재전송을 반영해 실제 처리율과 Goodput을 순차적으로 산출한다.

---

## Ⅳ. 특징

| 구분 | 대역폭 | 처리율(Throughput) | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 정의 | 이론적 최대 전송 용량 | 실제 측정된 전송·처리량 | bps, TPS, RPS 단위 |
| 결정 요인 | 물리 매체·인터페이스 규격 | 오버헤드, 혼잡, 자원 사용률 | 1G/10G NIC, ρ=λ/μ |
| 성격 | 고정된 상한값 | 조건에 따라 변동 | 실측 시점·구간별 변동 |
| 관련 개념 | Peak Capacity | Goodput(유효 처리율) | Goodput ≤ Throughput ≤ Bandwidth |

> 요약: 대역폭은 고정 상한, 처리율은 실측 변동값이며 Goodput은 그중 유효 데이터만 반영한 값이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 사양서 기준(대역폭) | 실측 기준(처리율) | 선택 기준 |
|:---|:---|:---|:---|
| 용도 | 회선·장비 선정 시 상한 참고 | 실제 서비스 용량 산정 근거 | 용량 산정은 실측 처리율 우선 |
| 리스크 | 과다 산정으로 실서비스 병목 미반영 | 측정 조건(부하·혼잡) 따라 변동 | 부하테스트로 재검증 필요 |
| 관리 지표 | 규격서 bps 수치 | 실측 bps·TPS, 재전송률 | 실측치와 사양치 격차 모니터링 |

> 요약: 회선·장비 선정은 대역폭, 서비스 용량 산정은 실측 처리율을 기준으로 판단한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 대역폭 과신 | 사양서 수치를 실사용치로 오인 | 실측 처리율 기반 용량 산정 | 실측 bps, 사양 대비 달성률 |
| 오버헤드 미반영 | 프로토콜 헤더·혼잡 제어 비용 간과 | 오버헤드 비율 사전 실측 후 여유율 반영 | 오버헤드 비율, 여유 용량 |
| Goodput 저하 | 재전송·오류율 증가 | 오류 원인 분석, 회선 품질·혼잡 제어 튜닝 | 재전송률, 오류율 |

> 요약: 대역폭 과신과 오버헤드 미반영은 실서비스 병목으로 이어지므로 실측 기반 용량 산정이 필요하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리율 달성률 | 대역폭 대비 목표 처리율(예: 80% 이상) | iperf, 인터페이스 카운터 |
| 오버헤드 비율 | 목표 오버헤드 이내 유지 | 패킷 캡처, 프로토콜 분석 |
| Goodput 비율 | 재전송률 목표치 이하 | 회선 품질 모니터링 |

> 요약: 도입 후 성공 여부는 처리율 달성률, 오버헤드 비율, Goodput 저하 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 회선·장비 선정 시 사양서 대역폭과 별도로 실측 처리율 데이터를 확보해 용량 산정에 반영함
2. 부하테스트로 오버헤드·혼잡 제어 영향을 실측해 실제 처리율과 대역폭 간 격차를 문서화함
3. Goodput 저하 시 재전송률·오류율을 모니터링해 회선 품질과 혼잡 제어 파라미터를 조정함

**결론 (2줄):**
- 기술사 판단: 용량 산정은 대역폭이 아닌 실측 처리율과 Goodput을 기준으로 수행해야 함
- 향후 방향: 실시간 트래픽 모니터링과 오토스케일링을 연계해 처리율 저하를 사전 탐지하는 체계로 확장해야 함
