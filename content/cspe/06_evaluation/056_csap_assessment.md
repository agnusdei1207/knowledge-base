# 📖 【암기용】 개념 완전 이해

> 목적: 클라우드 서비스 감리(055)와 CSAP가 왜 다른지, 공공기관이 클라우드를 쓰려면 왜 CSAP가 필요한지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 한국 공공기관이 이용할 클라우드 서비스가 물리·기술·관리적 보안 기준을 충족하는지 확인하는 국내 클라우드 보안 인증 제도
- **왜 필요한가**: 공공기관은 아무 클라우드 서비스나 도입할 수 없고, 국가 기준에 맞는 보안 통제가 검증된 서비스만 이용해야 하므로 서비스 자체에 대한 사전 인증이 필요하다
- **핵심 직관**: 식품 안전 인증마크처럼, CSAP는 클라우드 서비스라는 "제품"이 국내 공공 이용 기준에 맞는 보안 통제를 갖췄음을 인증기관이 확인해 주는 마크다

## 깊이 이해
- **배경·문제의식**: 공공기관이 개별적으로 클라우드 공급자의 보안 수준을 매번 검증하는 것은 비효율적이므로, 중앙 인증기관이 한 번 심사해 여러 공공기관이 결과를 공유하는 구조가 필요했다
- **작동 원리**: 인증기관이 클라우드 서비스 공급자의 물리적 보안(데이터센터 접근통제), 기술적 보안(암호화·접근통제·로깅), 관리적 보안(보안 조직·정책·사고 대응 체계)을 기준에 따라 심사하고 인증서를 발급한다
- **비유**: CSAP는 특정 사업(055의 클라우드 서비스 감리 대상)을 보는 것이 아니라, 그 사업이 사용하려는 클라우드 서비스 자체가 애초에 신뢰할 만한지를 미리 검증한 인증마크다
- **구체 예시**: 공공기관이 SaaS 도입을 검토할 때 해당 서비스가 CSAP 인증을 받지 않았다면 우선 도입 대상에서 제외되거나 별도 보안성 검토를 추가로 거쳐야 한다
- **흔한 오해·주의점**: CSAP는 ISO/IEC 27001이나 CSA STAR 같은 국제 정보보호관리체계 인증과 별개의 제도다. ISO 27001은 조직의 정보보호관리체계 전반을 다루는 국제 표준이고, CSA STAR는 국제 클라우드 보안 얼라이언스가 운영하는 자율 평가·인증이며, CSAP는 국내 공공 클라우드 이용을 전제로 한 국가 인증 제도로 인증 주체와 적용 범위가 다르다

## 연결 개념
- 클라우드 서비스 감리(055) — 개별 사업 단위 점검, CSAP는 서비스 자체의 사전 인증이라는 차이
- ISO/IEC 25010(035) — 소프트웨어 품질 특성 국제 표준과 인증 성격 비교 대상
- TIA-942 Tier 등급(045) — 데이터센터 물리적 등급 인증과 클라우드 서비스 보안 인증의 대상 차이 비교

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CSAP 답안은 인증 목적, 물리·기술·관리 3영역 심사 구조, 국제 인증과의 차이를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSAP는 공공기관이 이용할 클라우드 서비스의 물리·기술·관리적 보안 수준을 국가 기준으로 검증하는 국내 인증 제도이다.
> 2. **가치**: 공공기관마다 개별 보안성 검토를 반복하지 않고 인증 결과를 공유해 도입 절차를 표준화한다.
> 3. **판단 포인트**: 서비스 자체의 사전 인증(CSAP)과 개별 사업 단위 감리(클라우드 서비스 감리)는 검증 대상과 시점이 다르다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인증 목적 이해 확인 | 공공 클라우드 이용 전제 국가 인증 제도 | CSAP를 국제 표준 인증과 혼동 |
| 심사 영역 이해 확인 | 물리·기술·관리적 보안 3영역 심사 | 기술적 보안만 언급하고 관리적 보안 누락 |
| 유사 제도 구분 확인 | ISO 27001·CSA STAR와 적용 범위·주체 차이 | 모든 보안 인증을 동일한 것으로 서술 |

> 요약: 이 문제는 CSAP 심사 항목 나열보다 인증 목적과 국제 인증 대비 범위·주체 차이를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 공공기관용 클라우드 서비스의 물리·기술·관리적 보안 수준을 검증하는 국내 인증 제도
- 배경: 공공기관별 개별 보안성 검토는 중복 비용이 크고 검증 기준이 기관마다 달라질 위험이 있음
- 필요성: 중앙 인증기관의 단일 심사로 공공 클라우드 도입 기준을 표준화하고 신뢰 가능한 서비스만 이용하게 해야 함

---

## Ⅱ. 구조 및 구성요소

```text
클라우드 서비스 공급자 신청 -> 물리적 보안 심사 -> 기술적 보안 심사
  -> 관리적 보안 심사 -> 인증 발급 -> 사후 점검
```

| 구성요소 | 역할 | 확인 산출물 |
|:---|:---|:---|
| 물리적 보안 심사 | 데이터센터 접근통제, 재해 대비 시설 확인 | 시설 점검 보고서 |
| 기술적 보안 심사 | 암호화, 접근통제, 로깅·모니터링 확인 | 기술 통제 점검 결과서 |
| 관리적 보안 심사 | 보안 조직, 정책, 사고 대응 체계 확인 | 보안 정책·대응 절차서 |
| 사후 점검 | 인증 유지를 위한 주기적 재심사 | 사후관리 점검 결과서 |

> 요약: CSAP는 물리-기술-관리 3영역을 심사해 인증을 발급하고 사후 점검으로 유지 여부를 관리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
공급자 신청 -> 서류·현장 심사 -> 물리/기술/관리 통제 검증
  -> 인증위원회 심의 -> 인증서 발급 -> 공공기관 도입 시 확인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---|:---|:---|
| 1 | 공급자가 인증 신청서와 보안 통제 문서 제출 | 신청 요건 충족 여부 |
| 2 | 물리·기술·관리 통제를 기준별로 심사 | 통제 항목 충족률 |
| 3 | 심의를 거쳐 인증서 발급 여부 결정 | 미비 사항 시정 완료 여부 |
| 4 | 공공기관은 조달 시 인증 여부를 확인 후 도입 | 유효 인증서 확인 |

> 요약: CSAP는 서류·현장 심사와 통제 검증을 거쳐 인증서를 발급하고, 공공기관은 도입 시 이를 확인한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 공공기관별 반복 보안성 검토를 인증 하나로 대체 | 도입 절차 표준화 |
| 한계 | 인증 시점 기준 심사이므로 사후 보안 변화는 별도 점검 필요 | 사후관리 주기 확인 |
| 비교 포인트 | 국제 표준 인증은 조직 관리체계 중심, CSAP는 국내 공공 이용 전제 서비스 인증 | 인증 주체·적용 범위 차이 |

> 요약: CSAP는 도입 절차를 표준화하지만 인증 이후 보안 수준 유지는 사후관리 점검으로 별도 확인해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | ISO/IEC 27001 | CSA STAR | CSAP | 선택 기준 |
|:---|:---|:---|:---|:---|
| 인증 주체 | 국제 표준화기구 기반 민간 인증기관 | 국제 클라우드 보안 얼라이언스 | 국내 지정 인증기관 | 서비스 이용 대상(국내 공공 여부) |
| 적용 범위 | 조직의 정보보호관리체계 전반 | 클라우드 보안 통제 자율/제3자 평가 | 국내 공공기관용 클라우드 서비스 보안 통제 | 이용 목적(민간 vs 공공) |
| 성격 | 임의 인증, 글로벌 통용 | 임의 평가, 글로벌 통용 | 공공 조달 시 사실상 필수 요건 | 조달 규정 준수 필요 여부 |

> 요약: 공공기관 클라우드 조달에는 CSAP가 사실상 필수 요건이고, ISO 27001·CSA STAR는 별도 목적의 국제 인증으로 병행 가능하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 인증 미보유 서비스 도입 시도 | 조달 담당자의 인증 요건 확인 누락 | 조달 단계 인증 여부 사전 확인 절차화 | 인증서 유효기간 확인 건수 |
| 인증 이후 통제 약화 | 사후관리 점검 소홀 | 주기적 사후 심사와 변경사항 신고 의무화 | 사후 점검 이행률 |
| 국제 인증과 혼동 | 인증 성격 차이에 대한 이해 부족 | 조달·감리 교육에 인증 간 차이 명시 | 인증 오적용 사례 건수 |

> 요약: CSAP 리스크는 조달 단계 인증 확인, 사후관리 이행, 국제 인증과의 구분 교육으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 유효성 | 유효 기간 내 CSAP 인증서 보유 | 인증서 확인 |
| 통제 이행 | 물리·기술·관리 통제 항목 충족 | 심사 결과서 검토 |
| 사후관리 | 정기 사후 점검 이행 여부 | 사후관리 점검 이력 |

> 요약: CSAP 적용 성과는 인증 유효성, 통제 이행 수준, 사후관리 이행 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 공공 클라우드 조달 단계에서 CSAP 인증 유효 여부를 사전 확인 절차에 포함함
2. 물리·기술·관리 통제 심사 결과서를 근거로 서비스별 보안 수준 차이를 비교함
3. 인증 이후에는 사후관리 점검 이행 여부를 정기적으로 확인해 통제 약화를 예방함

**결론 (2줄):**
- 기술사 판단: 공공 클라우드 도입은 CSAP 인증 여부를 기본 요건으로 삼되 사후관리 이행까지 확인해야 함
- 향후 방향: 멀티클라우드·해외 클라우드 이용 확대에 맞춰 인증 상호인정 범위 확대 논의를 지속 검토해야 함
