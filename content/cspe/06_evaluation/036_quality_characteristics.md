# 📖 【암기용】 개념 완전 이해

> 목적: ISO/IEC 25010의 8개 품질 특성 중 실무에서 자주 쟁점이 되는 기능 적합성·성능 효율성·호환성·보안성을 하위 특성 단위까지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: ISO/IEC 25010의 8개 특성 중 기능 적합성(요구 기능 충족), 성능 효율성(자원 대비 처리 성능), 호환성(공존·연동), 보안성(기밀성·무결성 등)을 하위 특성 단위로 세분화한 것
- **왜 필요한가**: "기능이 맞다", "성능이 좋다"는 표현으로는 검수 기준이 되지 않는다. 각 특성을 하위 특성으로 쪼개야 어떤 항목이 미달인지 구체적으로 지적할 수 있다.
- **핵심 직관**: 요리 품평회에서 "맛있다" 대신 간·식감·플레이팅·재료 신선도를 항목별로 채점하는 것과 같다.

## 깊이 이해
- **기능 적합성(Functional Suitability)**: 요구된 기능을 명시된 조건에서 충족하는 정도를 뜻하며, 하위 특성은 완전성(Completeness)·정확성(Correctness)·적절성(Appropriateness)이다.
- **완전성·정확성·적절성**: 완전성은 요구 기능 전체가 구현되었는지, 정확성은 결과가 요구된 정밀도로 산출되는지, 적절성은 사용자가 과업을 효과적으로 수행하도록 기능이 배치되었는지를 본다.
- **성능 효율성(Performance Efficiency)**: 자원 사용량 대비 성능 수준을 뜻하며, 하위 특성은 시간 반응성(Time Behaviour)·자원 활용성(Resource Utilization)·용량(Capacity)이다.
- **시간 반응성·자원 활용성·용량**: 시간 반응성은 응답시간·처리시간, 자원 활용성은 CPU·메모리·네트워크 사용량, 용량은 처리 가능한 최대 한계치(동시 사용자 수 등)를 본다.
- **호환성(Compatibility)**: 다른 제품과 정보를 교환하거나 동일 환경을 공유할 수 있는 정도를 뜻하며, 하위 특성은 공존성(Co-existence)·상호운용성(Interoperability)이다.
- **공존성·상호운용성**: 공존성은 다른 소프트웨어와 자원(디스크·포트 등)을 다투지 않고 함께 동작하는지, 상호운용성은 서로 다른 시스템 간 데이터를 교환하고 처리할 수 있는지를 본다.
- **보안성(Security)**: 정보와 데이터를 인가된 접근 수준에 따라 보호하는 정도를 뜻하며, 하위 특성은 기밀성(Confidentiality)·무결성(Integrity)·부인방지성(Non-repudiation)·책임추적성(Accountability)·진위성(Authenticity)이다.
- **기밀성부터 진위성까지**: 기밀성은 인가된 자만 접근 가능한지, 무결성은 데이터가 변조되지 않았는지, 부인방지성은 행위를 사후에 부인할 수 없는지, 책임추적성은 행위 주체를 추적할 수 있는지, 진위성은 주체·자원의 신원이 증명 가능한지를 본다.
- **비유**: 기능 적합성은 "주문한 요리가 나왔는가", 성능 효율성은 "얼마나 빨리, 적은 인력으로 나왔는가", 호환성은 "다른 매장 포장 용기와도 맞는가", 보안성은 "주문자 본인에게만 전달되는가"에 해당한다.
- **흔한 오해·주의점**: 성능 효율성을 신뢰성(가용성·결함허용성)과 혼동하기 쉽지만, 성능 효율성은 자원 대비 처리 성능을, 신뢰성은 장애 상황에서의 기능 유지 능력을 다룬다.

## 연결 개념
- ISO/IEC 25010 — 8개 특성 전체 체계와 제품/사용 품질 모델 구분
- 결함 밀도·결함 제거율 — 기능 적합성(정확성)을 정량 측정하는 지표
- 테스트 커버리지 — 기능 적합성 검증의 실행 근거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 품질 특성 답안은 4개 특성의 정의, 하위 특성 목록, 측정 지표, 특성 간 혼동 방지를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 기능 적합성·성능 효율성·호환성·보안성은 ISO/IEC 25010의 8개 특성 중 각각 완전성/시간반응성/공존성/기밀성 등 하위 특성으로 세분화된다.
> 2. **가치**: 하위 특성 단위로 쪼개야 "무엇이 미달인가"를 구체적 수치·근거로 지적할 수 있다.
> 3. **판단 포인트**: 요구 기능 충족 여부는 기능 적합성, 자원 대비 처리 성능은 성능 효율성, 연동·공존은 호환성, 정보 보호는 보안성으로 구분해 측정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하위 특성 이해 확인 | 완전성/정확성/적절성, 시간반응성/자원활용성/용량 등 | 특성명만 나열하고 하위 특성 누락 |
| 측정 가능성 확인 | 각 특성을 정량 지표로 연결 | 추상 표현("좋다", "충분하다")으로 서술 |
| 특성 간 혼동 방지 확인 | 성능 효율성 vs 신뢰성, 호환성 vs 이식성 구분 | 유사 특성을 동일하게 서술 |

> 요약: 이 문제는 4개 특성의 하위 특성과 측정 지표를 정확히 짚어 혼동 없이 구분해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: ISO/IEC 25010 8개 특성 중 기능 적합성·성능 효율성·호환성·보안성을 하위 특성 단위로 세분화한 품질 기준
- 배경: 추상적 품질 표현으로는 계약 검수·감리 기준이 되지 않아 특성별 하위 특성과 측정 지표가 요구됨
- 필요성: 요구 기능 충족, 자원 대비 성능, 연동성, 정보 보호 수준을 각각 독립 지표로 판정해야 정확한 품질 개선이 가능

## Ⅱ. 구조 및 구성요소

```text
기능 적합성 -> 완전성/정확성/적절성
성능 효율성 -> 시간반응성/자원활용성/용량
호환성 -> 공존성/상호운용성
보안성 -> 기밀성/무결성/부인방지성/책임추적성/진위성
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 기능 적합성 | 요구 기능의 구현·정확성·적절성 판정 | 완전성·정확성·적절성 하위 특성 |
| 성능 효율성 | 자원 대비 처리 성능 판정 | 시간반응성·자원활용성·용량 하위 특성 |
| 호환성 | 타 제품과의 공존·연동 판정 | 공존성·상호운용성 하위 특성 |
| 보안성 | 정보 보호 수준 판정 | 기밀성·무결성·부인방지성·책임추적성·진위성 |

> 요약: 4개 특성은 각각 2~5개 하위 특성으로 세분화되어 정량 측정의 근거가 된다.

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 정의 -> 특성별 하위 특성 매핑
  -> 측정 지표·척도 설정 -> 테스트·측정 수행
  -> 특성별 점수 산출 -> 미달 항목 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 요구사항을 4개 특성의 하위 특성에 매핑 | 매핑 누락 여부 |
| 2 | 하위 특성별 측정 지표·목표치 설정 | 지표의 정량성 |
| 3 | 테스트·측정을 수행해 점수 산출 | 측정 데이터 신뢰도 |
| 4 | 미달 하위 특성을 식별해 개선 조치 | 목표 대비 충족률 |

> 요약: 품질 특성 평가는 하위 특성 매핑 후 정량 측정을 거쳐 미달 항목을 개선하는 절차다.

> 요약: 4개 특성은 각기 다른 측정 지표 체계를 가지므로 서로 대체할 수 없다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 성능 효율성 | 신뢰성(참고 특성) | 선택 기준 |
|:---|:---|:---|:---|
| 정의 | 자원 대비 처리 성능 | 장애 상황에서 기능 유지 능력 | 정상 동작 중 속도 문제인지, 장애 대응 문제인지 |
| 하위 특성 | 시간반응성·자원활용성·용량 | 성숙성·가용성·결함허용성·복구성 | 응답시간 지연은 성능, 서비스 중단은 신뢰성 |
| 측정 지표 | p95 latency, TPS, 리소스 사용률 | MTBF, 가용성 %, RTO/RPO | 지표 종류로 특성 구분 |

> 요약: 응답 지연 문제는 성능 효율성, 서비스 중단·복구 문제는 신뢰성으로 특성을 구분해 진단한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 특성 혼동 | 성능과 신뢰성, 호환성과 이식성을 동일 취급 | 하위 특성 정의로 재구분 | 특성별 정의 대조표 |
| 측정 누락 | 정성 평가만 수행, 정량 지표 미설정 | 특성별 목표 수치 사전 정의 | 지표 설정 완료율 |
| 보안 특성 편중 | 기밀성만 점검하고 부인방지·책임추적 누락 | 5개 하위 특성 전체 점검표 운영 | 하위 특성별 점검 완료 여부 |

> 요약: 리스크는 특성 혼동과 측정 누락이 핵심이므로 하위 특성 정의와 지표 사전 설정으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 기능 적합성 | 요구사항 추적 커버리지 100% | 요구사항-테스트 케이스 추적표 |
| 성능 효율성 | p95 응답시간, 자원사용률 목표치 이내 | 부하테스트, APM |
| 호환성 | 연동 API 성공률 목표치 이상 | 연동 테스트 결과 |
| 보안성 | 5개 하위 특성 점검 항목 충족률 100% | 보안 점검·감사 로그 |

> 요약: 성공 여부는 특성별 정량 지표 충족률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 요구사항 정의 단계에서 기능 적합성·성능 효율성·호환성·보안성별 하위 특성을 요구사항에 매핑함
2. 각 하위 특성에 정량 목표치를 설정하고 테스트·측정 결과로 충족 여부를 판정함
3. 성능 효율성과 신뢰성, 호환성과 이식성처럼 혼동되는 특성 쌍을 정의 기준으로 구분해 점검함

**결론 (2줄):**
- 기술사 판단: 품질 특성은 하위 특성 단위 정량 지표로 판정해야 검수·감리 근거로 활용 가능함
- 향후 방향: 성능·보안 하위 특성을 CI/CD 파이프라인에 자동 측정 항목으로 내재화해야 함
