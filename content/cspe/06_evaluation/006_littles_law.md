## 미리 알고가기

- $L$: 시스템 안에 머무는 평균 작업 수 또는 동시 사용자 수임
- $\lambda$: 단위 시간당 완료 또는 도착하는 평균 처리율임
- $W$: 작업이 시스템 안에 머무는 평균 시간임
- 안정 상태: 장기적으로 유입률과 처리율이 균형을 이루어 큐가 계속 커지지 않는 상태임
- Think Time: 사용자가 응답을 받은 뒤 다음 요청을 보내기까지 기다리는 시간임

## Ⅰ. 개요

- **정의/개념**: 리틀의 법칙은 안정 상태 시스템에서 평균 동시 작업 수가 처리율과 평균 체류 시간의 곱이라는 관계를 나타내는 성능 산식임
- **배경/필요성**: 동시 사용자 수, TPS, 응답시간은 따로 움직이는 값이 아니므로 용량 산정과 성능 시험 결과 검증에 서로를 연결하는 기준이 필요함

## Ⅱ. 특징

- 기본 산식은 $L = \lambda W$이며 세 값 중 두 값으로 나머지 값을 추정함
- 내부 구조를 몰라도 외부에서 관측한 처리율과 응답시간으로 평균 동시 처리량을 추정함
- 법칙은 평균 관계를 설명하므로 p99 지연이나 순간 폭주를 직접 설명하지는 않음
- 유입이 처리보다 계속 많아지는 불안정 상태에서는 산식을 그대로 적용하면 판단이 틀어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 리틀의 법칙 | 폐쇄형 사용자 모델 |
|:---|:---|:---|
| 산식 | $L = \lambda W$ | $X = \frac{N}{R + Z}$ |
| 대상 | 큐 안의 평균 작업 수와 체류 시간을 연결함 | 고정된 사용자 수에서 TPS를 계산함 |
| 주요 변수 | 동시 작업 수, 처리율, 응답시간 | 사용자 수 $N$, 응답시간 $R$, Think Time $Z$ |
| 활용 | 운영 지표 검증, 큐 규모 추정 | 부하 테스트 VUser 수와 목표 TPS 산정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 평균 동시 작업 수 $L$ | 시스템 내부에 동시에 머무는 요청 수로 thread, connection, queue 점유량과 연결됨 |
| 처리율 $\lambda$ | 단위 시간당 완료된 작업 수이며 TPS나 RPS로 측정함 |
| 평균 체류 시간 $W$ | 요청이 시스템에 머문 평균 시간이며 응답시간 또는 큐 체류 시간으로 해석함 |
| 안정 상태 조건 | 산식 적용 전에 유입과 처리가 균형인지 확인해 무한 큐 증가 상황을 배제함 |

```text
+-----------+     +-----------+     +-----------+
| 처리율 lambda | --> | 체류 시간 W | --> | 동시 작업 L |
+-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 지표 수집    | --> | 안정성 확인  | --> | 산식 적용    | --> | 용량 검증    |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **지표 수집**: TPS, 평균 응답시간, 동시 처리 수를 같은 기간에서 수집함
2. **안정성 확인**: 큐 길이와 오류율이 계속 증가하지 않는지 확인함
3. **산식 적용**: $L = \lambda W$ 또는 $X = \frac{N}{R + Z}$를 적용함
4. **용량 검증**: 계산값과 thread, connection, queue 한계를 비교함

## Ⅵ. 실무 적용 및 유의점

1. 부하 테스트에서는 목표 TPS를 만들 VUser 수를 산정하되 Think Time을 0으로 두면 실제 사용자 패턴과 달라지므로 $R$, $Z$, 목표 TPS를 함께 넣고 달성 TPS와 오류율로 확인함
2. 운영 분석에서는 TPS와 평균 응답시간으로 active request를 추정하되 큐가 계속 증가하면 안정 상태가 아니므로 queue depth와 timeout 증가 여부를 먼저 확인함

## Ⅶ. 결론

리틀의 법칙은 성능 달성을 약속하는 공식이 아니라 동시성, 처리율, 체류 시간을 같은 기준으로 묶어 용량 산정값이 맞는지 검산하게 하는 관계식임.
