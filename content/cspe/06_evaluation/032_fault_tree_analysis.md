## 📖 【암기용】 핵심 요약

*   **한눈에**: 이미 발생했거나 우려되는 최상위 장애(Top Event)를 꼭대기에 두고, **"왜 이 장애가 발생했을까?"**를 나무뿌리 캐듯 거꾸로 파고들며 원인들의 논리적 조합(AND/OR 게이트)을 밝혀내는 **하향식(Top-Down) 연역적 결함 분석 기법**.
*   **깊이 이해**:
    *   **배경**: 1961년, 미국 벨 연구소가 미니트맨 대륙간탄도미사일의 오발사 원인을 분석하기 위해 고안함. 우주선 폭발이나 원자력 발전소 멜트다운처럼 "절대 일어나서는 안 되는 최악의 결과" 하나를 정해놓고, 이를 유발하는 모든 가능한 경로를 차단하기 위해 만들어짐.
    *   **작동 원리**: "서버실 전체 전원 차단(Top Event)"이라는 결과에서 출발함. 
        $\to$ 원인은 무엇인가? "메인 전원 끊김 **AND** 보조 배터리(UPS) 고장". 
        $\to$ 메인 전원은 왜 끊겼나? "변전소 고장 **OR** 건물 인입선 단선". 
        이렇게 AND/OR 게이트 논리를 이용해 더 이상 쪼갤 수 없는 '기본 사건(Basic Event)'까지 가지를 쳐 내려감.
    *   **비유**: **명탐정의 범죄 수사**. 살인 사건이라는 '결과(Top Event)'를 먼저 두고, 범행 동기, 알리바이 부재, 흉기 확보 등의 '조건(원인)'들이 어떻게 결합(AND/OR)되어 살인으로 이어졌는지를 역추적하는 과정.
    *   **핵심 도출물 (최소 컷셋, Minimal Cut Set)**: Top Event를 일으키기 위해 필요한 **최소한의 기본 사건 조합**. 만약 단 1개의 기본 사건만으로 Top Event가 발생한다면, 그 사건이 바로 시스템의 아킬레스건인 SPOF(단일 고장점)임. 컷셋의 덩치를 키우는 것(AND 게이트 추가 = 이중화)이 곧 가용성 확보 전략임.
    *   **흔한 오해/주의점**: "부품 A가 고장나면 어떤 일이 벌어질까?"를 분석하는 것은 FTA가 아님 (이건 상향식인 FMEA의 영역). FTA는 철저하게 **"결과 $\to$ 원인"**으로 역추적해야 함.
*   **연결 개념**: FMEA(고장 모드 및 영향 분석), ETA(사건 나무 분석), SPOF(Single Point of Failure), 논리 게이트(AND/OR)

## 📝 【답안용】 서술 골격

> **💡 핵심 인사이트**
> *   **본질**: 시스템의 치명적 실패(Top Event)를 유발하는 하위 원인들의 상호작용을 Boolean 논리(AND/OR)로 구조화한 **연역적·하향식 리스크 모델링**.
> *   **가치**: 개별 부품의 고장뿐만 아니라 인간의 실수(Human Error), 환경적 요인까지 포괄적으로 분석하며, 복합 장애(Multiple Failures)의 발생 확률을 수학적으로 계산할 수 있음.
> *   **판단 포인트**: FTA(하향식/원인 규명)는 단독으로 쓰기보다 FMEA(상향식/부품 분석)와 상호 보완적으로 결합될 때 시스템 신뢰성 분석의 완전성(Completeness)이 확보됨.

### Ⅰ. 치명적 장애의 논리적 역추적, FTA(Fault Tree Analysis) 개요
*   **정의**: 시스템의 안전성 및 신뢰성을 분석하기 위해, 발생 가능한 최상위 결함 사건(Top Event)을 설정하고 이를 유발하는 하위 사건들의 논리적 관계를 Tree 형태로 전개하여 근본 원인을 규명하는 하향식 연역적 분석 기법.
*   **목적**: 대형 장애의 재발 방지 대책 수립, 최소 컷셋(Minimal Cut Set) 도출을 통한 SPOF 식별, 시스템 고장 확률의 정량적 계산.

### Ⅱ. FTA의 기호 및 논리적 전개 구조
*   **사건(Event) 기호**:
    *   **Top Event (직사각형)**: 분석의 대상이 되는 최상위 고장 사건.
    *   **Intermediate Event (직사각형)**: 하위 사건들의 조합으로 발생하는 중간 단계의 사건.
    *   **Basic Event (원)**: 더 이상 분해할 수 없는 최하위 원인 (예: 디스크 배드섹터, 작업자 오타).
*   **논리 게이트(Logic Gates)와 확률 계산 (Boolean Algebra)**:
    *   **AND Gate (곱사건)**: 하위 사건이 *모두* 발생해야 상위 사건이 발생. (이중화/병렬 시스템).
        *   $P(Top) = P(A) \times P(B)$
    *   **OR Gate (합사건)**: 하위 사건 중 *하나라도* 발생하면 상위 사건이 발생. (단일/직렬 시스템).
        *   $P(Top) = P(A) + P(B) - P(A)P(B)$

### Ⅲ. FTA 분석의 핵심: 최소 컷셋 (Minimal Cut Set)
*   **Cut Set (컷셋)**: 그 안에 포함된 모든 기본 사건들이 동시에 발생했을 때 Top Event를 유발하는 사건들의 집합.
*   **Minimal Cut Set**: 컷셋 중에서 더 이상 사건을 뺄 수 없는 최소한의 필수 조합.
*   **엔지니어링적 의미**:
    *   최소 컷셋의 크기(원소의 개수)가 `1`인 컷셋이 존재한다면, 그 기본 사건은 단일 고장만으로 시스템을 다운시키는 **SPOF(Single Point of Failure)**임. 즉시 이중화 조치(AND 게이트화)가 필요함.

### Ⅳ. FMEA, ETA, FTA의 신뢰성 분석 기법 비교
| 비교 항목 | FTA (Fault Tree Analysis) | FMEA (Failure Mode and Effects Analysis) | ETA (Event Tree Analysis) |
| :--- | :--- | :--- | :--- |
| **분석 방향** | **하향식 (Top-Down)** | **상향식 (Bottom-Up)** | **순방향 (Forward)** |
| **분석 논리** | **연역적** (결과 $\to$ 원인) | **귀납적** (부품 고장 $\to$ 시스템 영향) | **귀납적** (초기 사건 $\to$ 시나리오 분기) |
| **초점** | 특정 대형 장애(Top Event)의 원인 규명 | 모든 부품의 잠재적 고장 모드망라 | 고장 후 방어 기제의 성공/실패 경로 |
| **복합 장애** | 복수 원인의 조합(AND/OR) 분석 **우수** | 단일 부품 고장 분석에 치중 (복합 분석 취약) | 사건의 시간적 전개 순서 분석 우수 |

### Ⅴ. IT 시스템 아키텍처에서의 FTA 실무 활용
*   **장애 사후 분석 (Post-mortem Analysis)**: 대형 IT 장애(예: IDC 화재 시 DR 미작동) 발생 후, 재발 방지를 위해 "왜 이중화가 작동하지 않았나?"를 규명하는 데 핵심 도구로 사용.
*   **예방적 설계 검증**: 아키텍처 설계 단계에서 "결제 DB 동기화 실패"를 Top Event로 두고 컷셋을 뽑아내어, 설계상 누락된 이중화 지점(예: 스위치 단일 구성)을 찾아내어 보강함.
