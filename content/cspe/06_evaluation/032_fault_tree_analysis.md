## 미리 알고가기

- Top Event: 분석의 출발점이 되는 최상위 장애나 사고임
- Basic Event: 더 이상 분해하지 않는 최하위 원인 사건임
- Cut Set: Top Event를 일으킬 수 있는 기본 사건 조합임
- Minimal Cut Set: Top Event를 일으키는 최소한의 기본 사건 조합임

## Ⅰ. 개요

- **정의/개념**: FTA는 특정 장애나 사고를 Top Event로 놓고 그 결과를 만드는 하위 원인들의 논리 관계를 AND와 OR 게이트로 풀어 내려가는 하향식 결함 분석 기법임
- **배경/필요성**: 대형 장애는 단일 원인보다 복수 조건의 결합으로 발생하는 경우가 많으므로, 이미 드러난 결과에서 출발해 어떤 조합이 사고를 만들었는지 구조적으로 추적할 수 있는 방법이 필요함

## Ⅱ. 특징

- 결과에서 원인을 찾아 내려가는 연역적 방식이라 특정 대형 장애 분석에 적합함
- 복합 원인의 조합과 단일 장애점을 동시에 드러낼 수 있어 취약 경로 식별에 강함
- 논리 게이트를 통해 정성 분석뿐 아니라 확률 계산도 가능하지만 입력 사건 정의가 모호하면 해석이 흔들림
- 설계 단계의 예방 분석과 사고 후 원인 분석에 모두 쓸 수 있으나 범위 설정이 지나치게 넓으면 관리가 어려워짐

## Ⅲ. 종류 및 비교

| 판단 기준 | FTA | FMEA |
|:---|:---|:---|
| 분석 방향 | 결과에서 원인을 내려가는 하향식 분석임 | 부품이나 공정에서 영향으로 올라가는 상향식 분석임 |
| 강점 | 복합 원인 조합과 최소 컷셋 분석에 강함 | 개별 고장 모드의 예방 점검에 강함 |
| 출발점 | Top Event가 명확할 때 효과적임 | 구성 요소 목록이 명확할 때 효과적임 |
| 주요 활용 | 대형 사고 원인 규명, 아키텍처 취약점 분석에 적합함 | 설계 초기 위험 목록화와 개선 우선순위 선정에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Top Event | 분석 대상이 되는 최상위 장애이며 트리 전체의 방향을 정함 |
| Intermediate Event | 여러 하위 원인이 결합해 나타나는 중간 단계 사건임 |
| Basic Event | 장비 고장, 설정 오류, 운영 실수처럼 더 이상 분해하지 않는 원인 단위임 |
| 논리 게이트 | AND는 모든 조건이 동시에 필요함을, OR은 하나만 있어도 충분함을 나타냄 |

```text
+-------------+     +-------------+     +-------------+
| Top Event   | --> | 논리 게이트 전개 | --> | Basic Event 도출 |
+-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| Top Event 정의 | --> | 하위 원인 분해  | --> | 게이트 연결 정리 | --> | 컷셋/확률 분석  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **Top Event 정의**: 어떤 장애를 분석할지 명확히 정함
2. **하위 원인 분해**: 직접 원인과 간접 원인을 단계적으로 나눔
3. **게이트 연결 정리**: 원인들이 동시에 필요한지, 하나면 충분한지 논리 관계를 정함
4. **컷셋과 확률 분석**: 최소 컷셋과 사고 경로를 도출해 취약 지점을 찾음

## Ⅵ. 실무 적용 및 유의점

1. 데이터센터 정전이나 핵심 서비스 중단 같은 대형 장애는 FTA로 분석하되 Top Event를 지나치게 넓게 잡으면 원인 구조가 흐려지므로 범위를 명확히 하고 최소 컷셋과 최상위 사고 확률로 확인함
2. 설계 검토 단계에서는 SPOF와 공통 원인 고장을 찾는 데 유용하지만 입력 사건의 독립성 가정이 과도하면 계산이 왜곡될 수 있으므로 실제 장애 이력과 보완 분석을 함께 보고 컷셋 도출 범위와 검토 지적 조치율로 확인함

## Ⅶ. 결론

FTA의 핵심은 장애를 많이 나열하는 데 있지 않고 특정 사고를 만드는 최소 원인 조합을 드러내어 취약 경로를 끊는 데 있음.
