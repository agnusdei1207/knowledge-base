## 미리 알고가기

- 병렬 비율 $P$: 전체 실행시간 중 병렬 처리로 확장할 수 있는 비율임
- 처리 자원 수 $N$: 병렬 실행에 투입되는 코어, 프로세서, 노드 수임
- Weak Scaling: 처리 자원 증가에 맞춰 문제 크기도 키우면서 같은 실행시간 안의 처리량을 보는 방식임
- Scaled Speedup: 자원 증가로 더 큰 문제를 같은 시간에 처리하는 효과를 나타내는 가속비임

## Ⅰ. 개요

- **정의/개념**: 구스타프슨의 법칙은 처리 자원이 늘면 문제 크기도 함께 키울 수 있다는 전제에서 병렬 시스템의 확장 효과를 설명하는 성능 모델임
- **배경/필요성**: 대규모 분석, 시뮬레이션, AI 학습은 실행시간 단축보다 같은 시간 안에 처리할 데이터량과 정밀도가 판단 기준이므로 암달의 고정 크기 전제만으로는 부족함

## Ⅱ. 특징

- 대표 산식은 $S(N) = N - (1-P)(N-1)$로 표현함
- 순차 구간이 작고 데이터 분할이 가능할수록 처리 자원 증가 효과가 커짐
- 병렬 구간이 커져도 동기화, 통신, 데이터 skew가 커지면 선형 확장에서 벗어남
- 암달의 법칙과 충돌하는 법칙이 아니라 문제 크기 전제가 다른 해석 모델임

## Ⅲ. 종류 및 비교

| 판단 기준 | 암달의 법칙 | 구스타프슨의 법칙 |
|:---|:---|:---|
| 전제 | 문제 크기를 고정함 | 자원 증가에 맞춰 문제 크기를 키움 |
| 목표 | 실행시간을 얼마나 줄일지 봄 | 같은 시간에 얼마나 큰 문제를 풀지 봄 |
| 적합 업무 | 고정된 배치, 단일 작업 가속 | 대규모 분석, HPC, AI 학습 |
| 주요 제약 | 순차 구간 비율 | 통신 비용, 동기화, 데이터 skew |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 확장 가능한 작업 | 데이터 파티션이나 독립 작업으로 나눌 수 있는 병렬 구간임 |
| 순차 작업 | 초기화, 병합, 검증처럼 자원이 늘어도 줄지 않는 실행 구간임 |
| 통신·동기화 | 노드 간 데이터 교환과 barrier가 늘어나면 병렬 효과를 줄임 |
| 문제 크기 증가 | 더 큰 데이터, 더 높은 해상도, 더 많은 실험을 같은 시간 안에 처리하는 목표임 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 자원 증가    | --> | 문제 크기 확대 | --> | 병렬 처리    | --> | 결과 병합    |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 업무 분할성 확인 | --> | P 산정      | --> | 확장 효과 계산 | --> | 통신 비용 검증 |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **업무 분할성 확인**: 데이터와 작업을 독립 파티션으로 나눌 수 있는지 확인함
2. **$P$ 산정**: 실행시간 중 병렬 구간과 순차 구간 비율을 측정함
3. **확장 효과 계산**: 자원 수 증가에 따른 scaled speedup을 계산함
4. **통신 비용 검증**: shuffle, reduce, barrier가 확장 효과를 줄이는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 빅데이터 분석과 AI 학습에서는 노드를 늘리기 전에 데이터 분할 균형을 확인해야 하므로 partition skew, network throughput, GPU utilization을 함께 확인함
2. HPC 시뮬레이션에서는 해상도 증가가 목표일 수 있으므로 실행시간 단축만 보지 말고 동일 시간 내 처리 격자 수와 동기화 대기 시간을 함께 확인함

## Ⅶ. 결론

구스타프슨의 법칙은 병렬 시스템을 더 빨리 끝내는 도구로만 보지 않고 같은 시간 안에 더 큰 문제를 처리할 수 있는지 전제와 통신 비용으로 검증하게 함.

## 작성 근거(검토용)

- 암달의 법칙과 비교되는 키워드이므로 전제 차이를 가장 먼저 배치함
- 추상 평가어를 제거하고 문제 크기, 병렬 비율, 통신 비용으로 설명함
- 결론은 빠름이 아니라 같은 시간 내 처리 문제 크기라는 문맥상 맞는 판단어로 마무리함
