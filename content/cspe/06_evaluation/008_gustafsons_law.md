# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 구스타프슨의 법칙(Gustafson's Law)은 **코어 수에 맞춰 문제 크기를 키우는 관점의 확장성 법칙**으로, 확장 속도향상(scaled speedup) S = N - (1-p)(N-1)로 표현된다.
- **왜 필요한가**: 암달의 법칙(007 참조)의 비관적 상한이 "문제 크기 고정"이라는 비현실적 전제에서 나옴을 지적하고, 실제 대규모 병렬 시스템에서 코어가 늘면 다루는 데이터도 커진다는 현실을 반영하기 위함이다.
- **핵심 직관**: 사람을 100명 모았으면 원래 하던 작은 일이 아니라 100배 큰 일을 맡긴다. 직렬 부분 비중은 문제가 커질수록 상대적으로 작아져, speedup이 코어 수에 거의 비례해 계속 늘어난다.

## 핵심 용어 정리 (내부에 등장하는 것들)

007에서 정의한 p·N·speedup·직렬 비율은 (007 참조)로 위임하고, 이 파일은 "문제 크기가 코어에 맞춰 커진다"는 전제와 그로부터 나오는 확장 속도향상에 집중한다. 맨 위 상위 키워드가 정체성이다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 구스타프슨의 법칙(Gustafson's Law) | scaled speedup = N-(1-p)(N-1) | 코어 늘린 만큼 문제도 키우는 관점 |
| 확장 속도향상(scaled speedup) | 확대된 문제를 N코어로 푼 상대 성능 | 코어 수에 거의 비례해 증가 |
| 약한 확장성(weak scaling) | 코어당 문제 크기를 일정하게 유지하며 확장 | 1인당 작업량 고정, 인원만 늘림 |
| p (병렬 비율, 확장 기준) | 확대된 문제에서 병렬 실행 시간 비중 | 문제가 커질수록 1에 가까워짐 |
| 고정 시간 모델(fixed-time) | 실행 시간을 고정하고 문제 크기를 늘리는 전제 | 같은 시간에 더 큰 문제 처리 |
| 강한 확장성 대비 | 007은 문제 고정, 008은 문제 확대 | 같은 일 나눔 vs 더 큰 일 맡김 |

## 깊이 이해
- **배경·문제의식**: 1988년 John Gustafson이 Sandia 연구소의 1024노드 병렬 컴퓨터에서 speedup이 1000배 넘게 나오는 것을 관측하고, 암달의 법칙(007 참조)이 예측한 상한과 모순됨을 발견했다. 원인은 전제 차이였다 — 실무에서 코어를 늘리는 이유는 같은 문제를 빨리가 아니라 더 큰 문제를 같은 시간에 풀기 위해서라는 통찰이다.
- **작동 원리(어떻게+왜)**: N코어에서 실제로 걸린 시간을 1로 두고, 그중 직렬 비중을 (1-p), 병렬 비중을 p로 본다. 이 작업을 1코어로 한다면 병렬 부분은 N배 시간이 걸리므로 총 (1-p)+p·N이 된다. scaled speedup은 그 비율, 즉 (1-p)+pN = N-(1-p)(N-1)이다. 문제(=병렬 부분)가 N에 비례해 커지므로 직렬 비중이 상대적으로 희석되어 speedup이 N에 거의 선형으로 증가한다.
- **비유**: 요리사 100명을 모았다면 원래의 1인분이 아니라 100인분 연회를 같은 시간에 차린다. 간 보기 같은 직렬 공정은 100인분에서도 비슷한 시간이라, 전체에서 차지하는 비중이 1/100로 줄어 병렬 이득이 거의 그대로 살아난다.
- **구체 예시(워크드)**: p=0.9, N=8일 때 scaled speedup = 8 - 0.1×(8-1) = 8 - 0.7 = 7.3배. 같은 p·N에서 암달은 4.7배가 상한이었다(007). N=1024면 1024 - 0.1×1023 = 1024 - 102.3 = 921.7배로 코어 수에 근접한다. 즉 문제를 키우는 관점에서는 상한이 사실상 사라진다.
- **흔한 오해·주의점**: ① 암달과 구스타프슨이 모순되는 별개 법칙이라는 오해 — 같은 산술을 다른 전제(문제 고정 vs 확대)로 본 것일 뿐 둘 다 옳다. ② "구스타프슨이면 무한 확장"이라는 오해 — 문제를 키울 수 있고(대규모 데이터·해상도) 통신 오버헤드가 억제될 때만 성립한다. ③ 문제를 키울 수 없는 응답시간 민감 작업(단건 트랜잭션 지연)에는 여전히 암달의 상한(007)이 지배한다.

## 연결 개념
- 암달의 법칙(007) — 문제 고정 시 상한 1/(1-p)을 주는 대비 법칙, 전제 차이로 결론이 갈림
- HW 사이징(013) — 데이터 규모 증가형 워크로드의 코어 확장 근거로 약한 확장성 활용
- 벤치마크 SPEC·TPC·LINPACK(014) — 대규모 병렬 벤치마크가 문제 크기를 키우는 약한 확장성으로 성능 측정

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 구스타프슨의 법칙은 코어에 맞춰 문제를 키우는 관점의 scaled speedup = N-(1-p)(N-1)으로, 코어 수에 거의 비례해 확장됨.
> 2. **가치**: 암달의 비관적 상한이 문제 고정 전제에서만 성립함을 밝혀, 대규모 데이터 병렬 시스템의 실측 확장성을 설명함.
> 3. **판단 포인트**: 문제를 키울 수 있고 지연이 아닌 처리량이 목표일 때 적용하며, 응답시간 민감 작업엔 암달 상한이 우선함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산식·전제 정의 확인 | S=N-(1-p)(N-1)과 문제 확대 전제 | 문제 고정 전제로 서술, 암달과 혼동 |
| 암달과의 관계 확인 | 같은 산술·다른 전제로 결론 갈림 | 두 법칙을 모순으로 단정 |
| 적용 조건 확인 | 문제 확대 가능·처리량 목표일 때 | 무한 확장 가능으로 단정 |

> 요약: 산식뿐 아니라 "문제 확대"라는 전제와 암달과의 전제 차이, 적용 한계를 함께 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 코어 수에 맞춰 문제 크기를 키울 때 scaled speedup이 N-(1-p)(N-1)로 코어에 거의 비례하는 법칙
- 배경: 1988년 Gustafson이 1024노드에서 관측한 고배율 speedup으로 암달 상한(007 참조)의 전제 한계를 지적
- 필요성: 데이터 규모가 코어와 함께 커지는 대규모 병렬 워크로드의 실제 확장성을 설명·예측하기 위함

---

## Ⅱ. 구조 및 구성요소

- scaled speedup 산출 구조(선형 구조도):

```text
N코어 실제 시간 = 직렬(1-p) + 병렬(p) [문제는 N에 비례해 확대됨]
  -> 1코어 환산 시간 = (1-p) + p·N
  -> scaled speedup S = (1-p) + pN = N - (1-p)(N-1)
  -> N 증가 시 S는 N에 거의 선형
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 직렬 부분 (1-p) | 문제가 커져도 거의 불변 | 커진 문제서 비중 희석 |
| 병렬 부분 p | 문제 크기와 함께 N배 확대 | scaled speedup을 견인 |
| 프로세서 수 N | 문제 크기와 동반 증가 | speedup의 사실상 상한 |
| scaled speedup S | 확대 문제의 상대 성능 | N-(1-p)(N-1) |

> 요약: 병렬 부분이 N에 비례해 커져 직렬 비중이 희석되므로 speedup이 N에 거의 선형으로 증가함.

---

## Ⅲ. 동작원리 및 흐름도

- 확장성 판단 흐름(선형 흐름도):

```text
워크로드 확대 가능성 판단 -> 병렬 비율 p 측정
  -> S=N-(1-p)(N-1) 계산 -> 통신·동기화 오버헤드 반영
  -> 처리량 목표면 채택 / 지연 목표면 암달(007)로 전환
```

1. 대상 워크로드가 코어 증가에 맞춰 데이터·해상도를 키울 수 있는 처리량형인지 판단함
2. 확대된 문제 기준으로 병렬 실행 시간 비중 p를 측정함
3. scaled speedup S=N-(1-p)(N-1)을 계산하고 노드 간 통신·동기화 오버헤드를 감가함
4. 처리량이 목표면 약한 확장성으로 코어를 늘리고, 단건 지연이 목표면 암달의 상한(007)으로 판단을 전환함

---

## Ⅳ. 특징

- 코어 수에 맞춰 문제 크기를 키우는 약한 확장성 관점으로, 암달의 문제 고정 전제와 정반대임
- scaled speedup이 코어 수 N에 거의 선형으로 증가해 대규모 병렬에서 상한이 사실상 사라짐
- 직렬 부분은 문제가 커질수록 상대 비중이 희석되어 병렬 이득을 잠식하지 않음
- 실제 성립은 문제를 키울 수 있고(대용량 데이터·고해상도) 통신 오버헤드가 억제될 때로 한정됨
- 처리량 극대화가 목표인 HPC·빅데이터에 부합하며, 단건 응답시간 단축에는 부적합함

---

## Ⅴ. 심화 비교 및 적용 판단

- 암달 vs 구스타프슨(전제·결론 차이):

| 구분 | 암달의 법칙(007) | 구스타프슨의 법칙 |
|:---|:---|:---|
| 문제 크기 전제 | 고정(강한 확장성) | 코어에 비례 확대(약한 확장성) |
| speedup 산식 | 1/((1-p)+p/N) | N-(1-p)(N-1) |
| N→∞ 결과 | 상한 1/(1-p)로 포화 | N에 거의 선형, 상한 사실상 없음 |
| 적합 목표 | 단건 지연 단축 | 대규모 처리량 극대화 |
| p=0.9, N=8 예 | 약 4.7배 | 약 7.3배 |

> 요약: 두 법칙은 모순이 아니라 문제 고정이냐 확대냐의 전제 차이이며, 지연 목표는 암달·처리량 목표는 구스타프슨을 적용함.

- 리스크와 대응(불릿):
  - 전제 오적용 → 지연 민감 작업에 구스타프슨 적용 → 목표가 처리량인지 지연인지 먼저 확정(확인: SLA 지표 유형)
  - 통신 오버헤드 무시 → 노드 증가 시 동기화 비용 급증 → 통신량 모델에 반영해 실효 speedup 산정(확인: 노드 간 대역폭·지연)
  - 문제 확대 불가 → 데이터가 안 커지는데 약한 확장성 가정 → 실제 확장 가능 규모 검증(확인: 데이터 증가 여지)

---

## Ⅵ. 실무 적용 및 결론

- 적용 방안:
  1. 대규모 시뮬레이션·딥러닝 학습처럼 데이터·해상도를 키우는 워크로드는 scaled speedup으로 코어·노드 증설 규모를 산정함
  2. LINPACK·HPCG 등 약한 확장성 벤치마크(014)로 노드 확장 시 실효 speedup과 통신 오버헤드 감쇠를 실측해 검증함
  3. 처리량형은 구스타프슨, 단건 응답시간형은 암달(007)로 워크로드를 분류해 확장 전략을 이원화함
- 결론:
  - 코어 증설 효과는 문제를 키울 수 있느냐에 좌우되므로, 처리량 목표면 약한 확장성으로 대규모 확장을 정당화함
  - 통신·동기화 오버헤드가 코어 증가를 상쇄하는 지점을 실측해 확장 한계를 재조정할 필요가 있음
