# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 큐잉 이론(**대기행렬 이론**)은 도착률 λ과 서비스율 μ을 입력받아 **대기열 길이·대기시간을 확률적으로 예측하는 성능 모델**로, 서버 수에 따라 M/M/1(단일 서버)·M/M/c(다중 서버)로 나뉜다.
- **왜 필요한가**: 목표 응답시간을 지키려면 서버를 몇 대 둬야 하는지, 자원을 몇 %까지 채우면 대기가 폭증하는지를 감이 아니라 수식으로 사전 계산해야 과투자·포화 장애를 막기 때문이다.
- **핵심 직관**: 손님 오는 속도(λ) 대비 창구 처리 속도(μ)의 비율(ρ)이 정해지면 줄 길이가 수식으로 결정되고, ρ가 1에 가까워지면 줄이 절벽처럼 급증한다 — 큐잉 이론은 이 관계를 서버 수까지 넣어 정량화한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

기초 큐잉 변수(λ·μ·ρ·Wq)의 상세 정의는 002(응답시간 분해)에 있으므로, 여기서는 그것을 모델로 확장하는 데 필요한 표기에 집중한다. 맨 위 상위 키워드가 이 개념의 정체성이다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 대기행렬 이론(Queuing Theory) | 도착·서비스를 확률로 보고 대기 지표를 예측하는 이론 | 줄 서기를 수학으로 예측하는 학문 |
| Kendall 표기 A/B/c | 도착분포/서비스분포/서버 수를 3칸으로 표기하는 규칙 | "M/M/1" = 랜덤도착/랜덤처리/창구 1개 |
| M (Markovian) | 도착은 포아송, 서비스는 지수분포(무기억성)라는 가정 | 다음 손님이 언제 올지 과거와 무관 |
| λ(도착률) | 단위 시간당 도착 요청 수 (002 참조) | 1초에 손님 8명 도착 |
| μ(서비스율) | 서버 1대가 단위 시간당 처리 가능한 수 (002 참조) | 창구 1개가 1초에 10명 처리 |
| ρ(이용률) | 서버가 바쁜 비율. M/M/1은 λ/μ, M/M/c는 λ/(cμ) | 창구가 쉬지 않고 일한 시간 비율 |
| c(서버 수) | 하나의 대기열을 공유하는 처리 창구 개수 | 은행 공용 대기줄 뒤의 창구 3개 |
| L (계 내 평균 수) | 시스템 안에 있는 평균 요청 수(대기+처리) | 매장 안 전체 손님 평균 |
| Lq (대기열 길이) | 큐에서 대기만 하는 평균 요청 수 | 줄에 서 있는 평균 인원 |
| W (평균 체류시간) | 도착~완료까지 총 시간 = Wq + 1/μ | 입장~퇴장 전체 시간 |
| Wq (평균 대기시간) | 큐에서 기다린 시간 (002 참조) | 줄 서서 기다린 시간 |
| Erlang C | M/M/c에서 도착 즉시 대기할 확률을 주는 공식 | "왔더니 줄 서야 할" 확률 |

## 깊이 이해
- **배경·문제의식**: 002에서 M/M/1 대기시간 Wq = ρ/(μ−λ)를 소개했지만, "이 식이 어디서 나오는가", "서버를 c대로 늘리면 어떻게 바뀌는가"는 다루지 않았다. 큐잉 이론은 이 산식들의 출처이자, 서버 수 c를 변수로 넣어 용량을 설계하는 도구다.
- **Kendall 표기로 모델을 읽는다**: A/B/c에서 A는 도착 분포, B는 서비스 분포, c는 서버 수다. M/M/1은 "포아송 도착·지수 서비스·서버 1대"라는 뜻이다. M은 무기억성(Markov) 가정으로, 대기 지표를 닫힌 형태(closed-form) 수식으로 풀 수 있게 해준다.
- **M/M/1 핵심 산식**: ρ = λ/μ이며 안정 조건은 ρ<1이다. 이때 계 내 평균 수 L = ρ/(1−ρ), 대기열 Lq = ρ²/(1−ρ), 체류시간 W = 1/(μ−λ), 대기시간 Wq = ρ/(μ−λ)이다. Wq 식은 002의 산식과 동일하며, 여기서는 그 유도 맥락(전체 지표 세트의 일부)까지 함께 본다.
- **ρ→1일 때 급증(가장 중요한 성질)**: L = ρ/(1−ρ)에 값을 넣으면 ρ=0.5→L=1, 0.8→4, 0.9→9, 0.95→19, 0.99→99. 이용률을 90%에서 95%로 5%p 올렸을 뿐인데 대기가 2배가 된다 — 자원을 "꽉 채우면" 효율적일 것 같지만, 포화 직전에 대기가 비선형으로 폭발한다. 실무에서 목표 이용률을 70~80%로 잡는 근거다.
- **M/M/c — 서버 풀링의 이득**: c대의 서버가 하나의 공용 대기열을 나눠 처리하면 이용률은 ρ = λ/(cμ)로 정의된다. 핵심은 "트래픽을 c개로 쪼갠 독립 M/M/1 c개"보다 "c대가 한 줄을 공유하는 M/M/c"의 대기시간이 훨씬 짧다는 점이다(대기 확률은 Erlang C 공식이 준다). 은행에서 창구마다 줄 서는 것보다 한 줄 서서 빈 창구로 가는 방식이 빠른 이유다.
- **비유**: 톨게이트에서 게이트마다 줄을 세우면(독립 M/M/1) 옆 줄은 비었는데 내 줄만 막힐 수 있다. 하이패스처럼 한 줄로 모아 빈 게이트로 보내면(M/M/c) 유휴 창구 없이 흘러 평균 대기가 준다.
- **구체 예시(워크드)**: λ=8건/s, μ=10건/s인 서버.
  - M/M/1: ρ=0.8, W=1/(10−8)=0.5s, Wq=0.8/(10−8)=0.4s, L=0.8/0.2=4건.
  - 트래픽이 λ=18로 늘면 서버 1대(μ=10)로는 ρ=1.8>1 → 불안정(대기열 무한 발산). 서버를 c=2로 하면 ρ=18/(2×10)=0.9로 안정권에 들어 처리 가능해진다.
- **흔한 오해·주의점**: ① ρ<1은 필수 안정 조건이다 — ρ≥1이면 대기열이 무한히 쌓여 서비스 불능이 된다. ② M/M/c의 ρ는 전체가 아니라 서버 1대당 이용률(λ/cμ)이다. ③ M 가정(포아송·지수)이 깨지면(예: 서비스시간 편차가 큼) 실제 대기는 M/M/1 예측보다 나빠질 수 있어, 모델은 낙관적 하한 추정치로 쓴다.

## 연결 개념
- 응답 시간 분해(002) — Wq·Ws 정의와 ρ→1 급증의 기초 관점(본 파일이 그 산식의 출처)
- 리틀의 법칙(006) — L=λW·Lq=λWq로 대기 인원과 대기시간을 잇는 항등식(큐잉 산식 유도의 다리)
- 병목 분석(004) — ρ→1로 포화한 자원을 병목으로 식별하는 진단에 큐잉 결과를 활용

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 큐잉 이론은 λ·μ·서버 수 c로 대기지표(Wq·Lq·W·L)를 예측하는 모델로, M/M/1(단일)·M/M/c(다중 서버)로 구분됨.
> 2. **가치**: 목표 응답시간을 만족하는 최소 서버 수와 안전 이용률을 사전 계산해 용량을 설계할 수 있음.
> 3. **판단 포인트**: 이용률 ρ가 1에 근접하면 대기가 비선형 급증하므로 목표 이용률을 70~80%로 두고, 트래픽 증가는 서버 풀링(M/M/c)으로 흡수함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대기행렬 모델 이해 확인 | Kendall 표기·M/M/1 산식·안정조건 ρ<1 | 산식 없이 개념만 서술 |
| 이용률-대기 관계 이해 | ρ→1 시 L·Wq 비선형 급증 | 이용률 상승을 성능 향상으로 단정 |
| 용량 설계 역량 확인 | M/M/c 풀링으로 최소 서버 수 산정 | 독립 M/M/1 c개와 M/M/c 혼동 |

> 요약: 산식과 ρ→1 급증, 서버 풀링 이득을 근거로 용량 판단을 보여야 함.

## Ⅰ. 개요 및 필요성

- 개요: λ·μ·서버 수로 대기열의 대기시간·길이를 확률적으로 예측하는 성능 모델
- 배경: 002가 소개한 M/M/1 산식의 출처이자, 서버 수 c를 변수로 확장한 상위 모델
- 필요성: 목표 응답시간을 지키는 최소 서버 수·안전 이용률을 감이 아닌 수식으로 산정해야 과투자·포화 장애를 예방함

---

## Ⅱ. 구조 및 구성요소

- 대기행렬 구조(선형 구조도):

```text
요청 도착(λ, 포아송) -> Queue(대기, Wq·Lq 발생)
  -> Server c대(μ, 지수서비스, ρ=λ/(cμ)) -> 처리 완료(W·L 산출)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 도착 과정(λ) | 단위 시간당 요청 유입 | 포아송 가정(M) |
| 대기열(Queue) | 서버 유휴 없을 때 요청 보관 | Lq·Wq 지표 산출 |
| 서버(c대, μ) | 요청 처리 자원 | 공용 큐 공유가 풀링 이득 |
| 이용률 ρ | 서버 바쁜 비율 λ/(cμ) | ρ<1이 안정 필수 조건 |

> 요약: 도착·대기열·다중 서버·이용률이 결합돼 대기지표를 산출함.

---

## Ⅲ. 동작원리 및 흐름도

- 대기지표 산출 흐름(선형 흐름도):

```text
λ·μ·c 입력 -> ρ=λ/(cμ) 계산 -> 안정성(ρ<1) 확인
  -> Lq 산출 -> Wq=Lq/λ, W=Wq+1/μ -> 목표 응답시간과 비교 -> c 재조정
```

1. λ·μ·서버 수 c를 입력해 이용률 ρ=λ/(cμ)를 계산하고 ρ<1 안정 여부를 확인함
2. M/M/1은 Lq=ρ²/(1−ρ), M/M/c는 Erlang C로 대기 확률·Lq를 산출함
3. 리틀의 법칙(006)으로 Wq=Lq/λ, W=Wq+1/μ를 도출함
4. W가 목표 응답시간을 넘으면 서버 수 c를 늘려 ρ를 낮추고 재계산함

---

## Ⅳ. 특징

- 이용률 ρ가 1에 근접하면 L=ρ/(1−ρ)로 대기가 비선형 급증함(0.9→9, 0.95→19)
- 안정 조건은 ρ<1이며, ρ≥1이면 대기열이 무한 발산해 서비스 불능이 됨
- M/M/c 풀링은 동일 트래픽을 독립 M/M/1 c개로 나눈 것보다 대기시간이 짧음
- M 가정(포아송·지수)이 깨지면 실제 대기가 예측보다 커져 모델은 낙관적 하한 추정치로 활용됨
- 포화 근처에서는 서버 1대 증설이 ρ를 크게 낮춰 대기를 급감시킴

---

## Ⅴ. 심화 비교 및 적용 판단

- 단일 서버 vs 다중 서버 모델 비교:

| 구분 | M/M/1 | M/M/c |
|:---|:---|:---|
| 서버 수 | 1대 | c대(공용 큐) |
| 이용률 정의 | ρ=λ/μ | ρ=λ/(cμ) |
| 대기 산식 | Lq=ρ²/(1−ρ) | Erlang C 기반 |
| 강점 | 계산 단순, 단일 자원 분석 | 풀링으로 대기 급감, 확장 설계 |
| 적용 | 단일 인스턴스 병목 진단 | 서버팜·스레드풀 용량 산정 |

> 요약: 단일 자원 분석은 M/M/1, 다중 서버 용량 설계는 M/M/c를 사용함.

- 리스크와 대응(불릿):
  - 이용률 과다 → ρ→1로 대기 폭증 → 목표 이용률 70~80% 설정·오토스케일링(확인: ρ, p95 변곡점)
  - 서버 분할 오설계 → 서버당 독립 큐로 유휴·편중 발생 → 공용 큐(M/M/c)·로드밸런서 분산(확인: 서버별 큐 편차)
  - 모델 과신 → 서비스시간 편차 큰데 M 가정 적용 → 부하테스트로 실측 보정(확인: 서비스시간 분산)

---

## Ⅵ. 실무 적용 및 결론

- 적용 방안:
  1. 부하테스트로 λ·μ를 실측한 뒤 M/M/c로 목표 p95를 만족하는 최소 서버 수·이용률을 산정함
  2. 오토스케일링 임계값을 ρ 급증 변곡점(대개 70~80%) 이전으로 설정해 포화를 예방함
  3. 로드밸런서를 공용 큐(단일 진입) 방식으로 구성해 서버 풀링 이득을 실현함
- 결론:
  - 큐잉 이론은 서버 수와 이용률로 대기를 예측해 용량을 수식 기반으로 설계하게 함
  - 실측 트래픽을 모델에 연동해 오토스케일링 임계값을 자동 산출하는 체계로 확장 필요
