# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 큐잉 이론(대기행렬 이론)은 요청의 도착(Arrival)과 서비스(Service)를 확률 모델로 정의하여, **시스템 내 대기 시간과 대기열 길이를 정량적으로 예측**하는 수학적 방법론이다.
- **왜 필요한가**: 서버를 무작정 늘리는 대신 "목표 응답시간을 달성하기 위해 최소 몇 대의 서버가 필요한가?", "이용률이 몇 %일 때 대기열이 폭증하는가?"에 대한 **수학적 근거(Sizing Reference)**를 제공하기 위함이다.
- **핵심 직관**: 은행에서 대기 시간이 길어지는 원인을 **손님이 오는 속도($\lambda$)**, **창구 직원의 업무 처리 속도($\mu$)**, **창구의 개수($c$)**의 상관관계로 풀어내는 것이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 기술적 포인트 |
|:---|:---|:---|
| **Kendall's Notation** | 큐잉 모델을 기술하는 표준 표기법 | $A / B / c$ 형식 (도착분포 / 서비스분포 / 서버수) |
| **M (Markovian)** | 포아송 도착 및 지수 서비스 분포 | 무기억성(Memoryless) 특성을 가짐 |
| **$\lambda$ (Arrival Rate)** | 단위 시간당 평균 도착 요청 수 | 유입 부하 (Load) |
| **$\mu$ (Service Rate)** | 서버 1대당 단위 시간당 평균 처리 수 | 자원 역량 (Capacity) |
| **$\rho$ (Utilization)** | 서버 이용률 | M/M/1: $\lambda / \mu$, M/M/c: $\lambda / (c\mu)$ |
| **$L_q$ (Queue Length)** | 큐에서 대기 중인 평균 요청 수 | 시스템 정체 정도의 척도 |
| **$W_q$ (Wait Time)** | 큐에서의 평균 대기 시간 | 002 키워드의 핵심 분석 대상 |

## 깊이 이해
- **이용률($\rho$)과 대기열의 관계 (Non-linear Explosion)**: M/M/1 모델에서 시스템 내 평균 고객 수 $L = \rho / (1-\rho)$이다. $\rho=0.9$이면 $L=9$, $\rho=0.99$이면 $L=99$로 급격히 증가한다. 이는 **"자원을 100%에 가깝게 쓰면 효율적일 것 같지만, 실제로는 대기 시간이 무한대로 발산한다"**는 성능의 역설을 보여준다.
- **M/M/1 vs M/M/c (Pooling Benefit)**:
  - **M/M/1**: 단일 대기열, 단일 서버. 계산이 간편하여 단일 컴포넌트 분석에 사용.
  - **M/M/c**: 단일 대기열을 $c$개의 서버가 공유. 여러 서버가 협업하므로 **부하 분산 효과(Pooling Effect)**로 인해 동일 이용률 대비 대기 시간이 M/M/1보다 훨씬 짧다. (은행 번호표 시스템이 효율적인 이유)
- **비유 (고속도로 톨게이트)**:
  - **M/M/1**: 1개의 차선만 있는 톨게이트. 앞 차가 밀리면 답이 없다.
  - **M/M/c**: 1개의 진입로 끝에 10개의 하이패스 차로가 있는 형태. 한 차로가 막혀도 다른 차로로 빠르게 빠질 수 있어 대기 시간이 획기적으로 줄어든다.
- **구체 예시 (Sizing 사례)**: $\lambda=80$, $\mu=100$일 때, $\rho=0.8$이다. 이때 서버를 1대에서 2대로 늘리면($c=2$), 개별 서버 이용률은 $0.4$로 낮아지며 대기 시간은 기하급수적으로 감소한다.

## 연결 개념
- **리틀의 법칙(006)**: $L = \lambda W$ 관계를 통해 대기열 길이와 시간을 상호 변환.
- **응답 시간 분해(002)**: 큐잉 이론을 통해 $W_q$를 정량적으로 산출.
- **병목 분석(004)**: 병목 지점이 M/M/1 모델의 어느 지점인지 식별.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 큐잉 이론은 유입 부하($\lambda$)와 처리 역량($\mu$, $c$)을 기반으로 대기 지표를 확률적으로 모델링하는 성능 예측 프레임워크임.
> 2. **임계점**: 이용률($\rho$)이 1에 도달하면 대기열($L_q$)과 대기시간($W_q$)이 수학적으로 무한 발산하므로, 안정적 운영을 위한 '여유 용량(Headroom)' 확보가 필수임.
> 3. **최적화**: 서버 풀링(Pooling) 효과를 극대화하는 M/M/c 모델을 지향하여 동일 자원 대비 대기 시간을 최소화하는 아키텍처 설계가 요구됨.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 큐잉 모델의 이해와 표기법 | Kendall's Notation ($M/M/1$, $M/M/c$) | 수식 없이 개념적 설명으로만 채우지 말 것 |
| 이용률에 따른 지연 분석 | $\rho \to 1$ 시 비선형적 폭발 현상 ($1/(1-\rho)$) | 이용률과 대기 시간이 선형 관계라고 오해 방지 |
| 시스템 설계 적용 역량 | 서버 풀링(Pooling)의 이점 및 용량 산정 활용 | M/M/1만 언급하지 말고 다중 서버(M/M/c)로 확장 |

## Ⅰ. 큐잉 이론(Queuing Theory)의 개요

### 1. 정의
- 요청의 도착, 대기, 서비스 과정을 확률 분포로 모델링하여 시스템의 성능 지표(대기시간, 대기열 길이)를 예측하는 수치 분석 기법

### 2. Kendall's Notation 기반 분류
- **M/M/1**: Poisson 도착, 지수 서비스 시간, 서버 1대 (기초 모델)
- **M/M/c**: Poisson 도착, 지수 서비스 시간, 서버 $c$대 (실무 다중 서버 모델)

---

## Ⅱ. 큐잉 이론의 주요 변수 및 산식 (M/M/1 기준)

### 1. 핵심 지표 산식

| 지표 | 산식 | 기술적 의미 |
|:---|:---|:---|
| **이용률 ($\rho$)** | $\lambda / \mu$ | 시스템 부하 포화도 (안정 조건: $\rho < 1$) |
| **시스템 내 평균 수 ($L$)** | $\frac{\rho}{1-\rho}$ | 대기 중인 요청 + 처리 중인 요청의 합 |
| **평균 대기열 길이 ($L_q$)** | $\frac{\rho^2}{1-\rho}$ | 순수하게 큐에서 대기 중인 요청 수 |
| **평균 대기 시간 ($W_q$)** | $\frac{\rho}{\mu(1-\rho)}$ | 자원 경합에 의한 지연 시간 |

### 2. 이용률($\rho$)에 따른 대기 지표 변화 (Saturation Graph)

```text
  Queue Length (Lq)
      ^
      |                   /
      |                  /  <-- ρ=0.99 (Lq ≈ 98)
      |                _/
      |            ___/     <-- ρ=0.9 (Lq ≈ 8.1)
      |________---          <-- ρ=0.5 (Lq ≈ 0.5)
      +---------------------> Utilization (ρ)
          0.5   0.8   1.0
```

---

## Ⅲ. M/M/c 모델과 서버 풀링(Pooling)의 효과

### 1. M/M/c의 개념
- 여러 대의 서버($c$)가 하나의 대기열(Common Queue)을 공유하여 요청을 처리하는 구조
- **산식 특징**: 이용률 $\rho = \lambda / (c \mu)$ 가 1보다 작아야 시스템이 안정됨

### 2. 독립 서버($c$개의 M/M/1) vs 통합 서버(1개의 M/M/c) 비교

| 구분 | $c$개의 독립 M/M/1 | 1개의 통합 M/M/c |
|:---|:---|:---|
| **구조** | 각 서버별 별도 큐 존재 | 하나의 공용 큐 공유 |
| **효율성** | 특정 서버만 붐비는 불균형 발생 가능 | 유휴 서버 없이 전체 자원 최적 활용 |
| **대기 시간** | 상대적으로 길어짐 | **Pooling 효과**로 대폭 단축 |
| **실무 적용** | 서버별 Local Queue 방식 | Load Balancer + Server Farm 방식 |

---

## Ⅳ. 큐잉 이론의 실무적 활용 방안

### 1. 용량 산정 및 확장성 설계 (Sizing)
- 목표 응답시간($W$)을 유지하기 위해 필요한 최소 서버 수($c$)를 역산하여 인프라 비용 최적화
- 오토스케일링(Auto-scaling)의 임계값(Threshold)을 Knee Point(대개 $\rho=0.7 \sim 0.8$)로 설정

### 2. 서비스 가용성 확보
- 트래픽 피크 시의 $L_q$를 예측하여 큐 오버플로우(Queue Overflow) 방지를 위한 적정 큐 사이즈(Buffer Size) 결정

## Ⅴ. 큐잉 모델 간 종합 비교

| 비교 항목 | M/M/1 | M/M/c | M/G/1 (참고) |
|:---|:---|:---|:---|
| **서버 수** | 1대 | $c$대 | 1대 |
| **서비스 분포** | 지수 분포 (Exponential) | 지수 분포 | 일반 분포 (General) |
| **주요 용도** | 단일 병목 지점 분석 | 클러스터/서버팜 설계 | 서비스 시간이 불규칙한 로직 분석 |
| **계산 복잡도** | 매우 낮음 | 중간 (Erlang-C 활용) | 높음 (P-K 산식 활용) |

## Ⅵ. 결론 및 제언

- 큐잉 이론은 시스템 성능을 **"희망"이 아닌 "데이터"**로 설계하게 해주는 강력한 무기임.
- 현실의 서비스 시간은 지수 분포를 따르지 않는 경우가 많으므로(예: 고정 처리 시간), M/M/1의 결과를 바탕으로 **부하테스트를 통한 실측 보정**을 병행하는 하이브리드 접근법 권고.
