# 📖 【암기용】 개념 완전 이해

> 목적: 대기행렬 모델이 서버 수와 이용률에 따라 대기시간을 어떻게 계산하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 도착과 서비스가 확률적으로 발생하는 시스템에서 대기행렬 길이·대기시간을 수학적으로 모델링하는 이론, M/M/1은 단일 서버, M/M/c는 다중 서버 모델
- **왜 필요한가**: 서버를 몇 대 두어야 목표 응답시간을 만족하는지 직관이 아닌 수식으로 산정해야 과소·과다 투자를 방지
- **핵심 직관**: 은행 창구가 1개면 M/M/1, 여러 개면 M/M/c이며, 창구 수가 늘수록 평균 대기시간은 줄지만 창구 1개당 여유는 줄어들 수 있음

## 깊이 이해
- **배경·문제의식**: 서버 용량 산정 시 평균 처리량만 보면 순간적인 도착 집중으로 인한 대기시간 폭증을 예측하지 못함
- **작동 원리**: Kendall 표기법 M/M/1은 도착이 포아송 과정(M, Markovian), 서비스시간이 지수분포(M), 서버 수가 1대인 모델이며, M/M/c는 서버가 c대인 일반화 모델로 Erlang C 공식을 사용
- **비유**: M/M/1은 창구 1개짜리 은행, M/M/c는 같은 대기줄을 여러 창구가 나눠 처리하는 은행에 대응
- **구체 예시**: 예시로 도착률 λ=8건/분, 서비스율 μ=10건/분인 M/M/1 시스템은 ρ=0.8이며, 서버를 2대(M/M/2, 각 μ=10)로 늘리면 동일 부하에서도 개별 서버 이용률과 대기시간이 크게 낮아짐
- **흔한 오해·주의점**: M/M/1과 M/M/c는 서버 수만 다른 것이 아니라 대기 확률(Erlang C) 계산 방식 자체가 다르므로 M/M/1 공식을 서버 수로 단순 나누어 M/M/c에 적용하면 안 됨

## 연결 개념
- 리틀의 법칙 — 큐잉 모델에서 산출된 L, Lq, W, Wq를 연결하는 공식
- 응답 시간 분해 — Wq(대기시간)와 서비스시간을 합쳐 응답시간을 구성
- 병목 분석 — ρ가 1에 근접하는 자원이 병목으로 식별되는 근거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 큐잉 이론 답안은 M/M/1·M/M/c 표기법 의미, 이용률·평균 대기시간 산식, 서버 수 증가 효과를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: M/M/1은 포아송 도착·지수 서비스·단일 서버, M/M/c는 동일 조건에서 서버가 c대인 대기행렬 모델이다.
> 2. **가치**: 도착률·서비스율만으로 평균 대기시간·대기행렬 길이를 사전에 계산해 서버 증설 효과를 정량 비교할 수 있다.
> 3. **판단 포인트**: 이용률 ρ가 1에 가까워질수록 대기시간이 급증하므로 서버 수 c는 ρ<1을 유지하는 선에서 산정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Kendall 표기법 이해 확인 | M/M/1(단일 서버), M/M/c(다중 서버)의 정확한 정의 | 두 모델을 서버 수 차이로만 단순화 |
| 이용률·대기시간 산식 확인 | ρ=λ/μ(M/M/1), ρ=λ/(cμ)(M/M/c) | ρ가 1 이상이면 시스템이 불안정하다는 조건 누락 |
| 서버 증설 효과 판단 확인 | c 증가 시 대기시간 감소, Erlang C로 계산 | M/M/1 공식을 단순히 c로 나눠 M/M/c에 적용 |

> 요약: 이 문제는 공식 암기보다 M/M/1·M/M/c 모델 조건과 서버 수가 대기시간에 미치는 영향을 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 확률적 도착·서비스 환경에서 대기행렬 길이와 대기시간을 수학적으로 모델링하는 이론
- 표기: M/M/1은 도착(M)·서비스(M) 모두 확률분포를 따르고 서버가 1대, M/M/c는 서버가 c대인 일반화 모델
- 필요성: 서버 증설 전 목표 대기시간을 만족하는 서버 수를 수식으로 사전 산정해야 과소·과다 투자를 방지

---

## Ⅱ. 구조 및 구성요소

```text
도착 과정(포아송, λ) -> 대기행렬(Queue)
  -> 서버 1대 처리(M/M/1, μ) 또는 서버 c대 처리(M/M/c, μ)
  -> 서비스 완료 -> 이용률(ρ)·대기시간(Wq) 산출
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 도착 과정 | 단위 시간당 평균 λ건 도착(포아송 분포) | 도착 간격은 지수분포 |
| 서비스 과정 | 서버 1대당 평균 μ건 처리(지수분포) | 서비스시간은 지수분포 |
| 서버 수(c) | M/M/1은 1대, M/M/c는 c대 | c 증가 시 Erlang C로 대기확률 계산 |
| 안정 조건 | ρ<1 유지 필요 | M/M/1: ρ=λ/μ, M/M/c: ρ=λ/(cμ) |

> 요약: 도착률·서비스율·서버 수를 입력하면 이용률과 대기시간을 산출할 수 있는 확률 모델이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
도착률(λ)·서비스율(μ)·서버 수(c) 정의 -> 이용률(ρ) 계산
  -> 안정성 확인(ρ<1) -> 평균 대기행렬 길이(Lq) 산출
  -> 평균 대기시간(Wq) 산출 -> 응답시간(W=Wq+1/μ) 도출
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | λ, μ, c 파라미터 정의 | 단위 시간당 도착·처리 건수 |
| 2 | 이용률 ρ 계산 및 안정성 확인 | ρ=λ/μ(M/M/1) 또는 ρ=λ/(cμ)(M/M/c), ρ<1 |
| 3 | 평균 대기행렬 길이 Lq 산출 | M/M/1: Lq=ρ²/(1-ρ), M/M/c: Erlang C 공식 |
| 4 | 평균 대기시간 Wq, 응답시간 W 산출 | Wq=Lq/λ(Little's Law), W=Wq+1/μ |

> 요약: 파라미터 정의 후 이용률을 계산하고, 안정 조건을 확인한 뒤 대기행렬 길이와 대기시간을 순차 산출한다.

---

## Ⅳ. 특징

| 구분 | M/M/1 | M/M/c | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 서버 수 | 1대 | c대(c≥2) | Kendall 표기법: 도착/서비스/서버수 |
| 이용률 | ρ=λ/μ | ρ=λ/(cμ) | ρ<1이어야 안정 상태 |
| 평균 대기행렬 길이 | Lq=ρ²/(1-ρ) | Erlang C 공식 기반 산출 | 단순 나눗셈으로 근사 불가 |
| 적용 예 | 단일 처리 스레드·단일 창구 | 서버 풀·멀티 스레드 워커 | 스레드 풀 크기 산정 |

> 요약: M/M/1은 단일 서버 모델, M/M/c는 다중 서버 모델로 대기행렬 계산 방식(Erlang C) 자체가 다르다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | M/M/1 적용 상황 | M/M/c 적용 상황 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 스레드·단일 커넥션 처리 | 스레드 풀·서버 풀 기반 처리 | 병렬 처리 자원 수로 모델 선택 |
| 계산 복잡도 | 폐형(closed-form) 공식으로 단순 | Erlang C 계산 또는 시뮬레이션 필요 | 서버 수 많으면 시뮬레이션 병행 |
| 확장성 판단 | 서버 1대 한계 도달 시 확장 필요 | 서버 수 c 증가로 대기시간 완화 | 목표 Wq 만족하는 최소 c 산정 |

> 요약: 단일 처리 자원은 M/M/1, 서버 풀 구조는 M/M/c로 모델링하며 서버 수 산정은 목표 대기시간 기준으로 결정한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 이용률 1 근접 | 도착률이 처리 용량에 근접(ρ→1) | 서버 증설 또는 도착률 제어(큐 제한) | ρ 값, 대기행렬 길이 추이 |
| M/M/c 오적용 | M/M/1 공식을 서버 수로 단순 나눔 | Erlang C 공식 또는 시뮬레이션 도구 사용 | 계산값과 실측값 비교 |
| 도착 분포 오가정 | 실제 도착이 포아송이 아닌 버스트성 | 실측 도착 분포 검증 후 모델 보정 | 도착 간격 분산, 버스트 계수 |

> 요약: 이용률 관리와 모델 적용 오류 방지를 위해 실측 데이터로 파라미터와 분포 가정을 검증해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 이용률 ρ | 0.7~0.8 이하 유지(운영 여유 확보 예시) | 자원 모니터링, 도착·처리 로그 |
| 평균 대기시간 | 목표 Wq 이내 | 큐 모니터링, APM |
| 모델 적합성 | 실측 도착·서비스 분포와 모델 가정 일치 | 통계 검정(적합도 검정) |

> 요약: 도입 후 성공 여부는 목표 이용률 유지, 대기시간 목표 충족, 모델 가정과 실측 분포의 일치도로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단일 처리 자원(단일 스레드·단일 커넥션 풀)은 M/M/1 모델로 이용률과 대기시간을 산정함
2. 서버 풀·스레드 풀 구조는 M/M/c 모델과 Erlang C 공식으로 목표 대기시간을 만족하는 최소 서버 수를 산정함
3. 실측 도착·서비스 데이터를 주기적으로 수집해 모델 가정(포아송·지수분포)의 적합성을 검증함

**결론 (2줄):**
- 기술사 판단: 서버 용량 산정은 평균 처리량이 아니라 큐잉 이론 기반 대기시간 예측으로 수행해야 함
- 향후 방향: 실시간 트래픽 패턴을 반영한 시뮬레이션·오토스케일링과 결합해 동적 서버 수 조정 체계로 발전시켜야 함
