## 미리 알고가기

- Failover: 주 노드 장애 시 대기 노드가 서비스를 이어받는 전환 절차임
- Failback: 복구된 원래 노드로 다시 역할을 되돌리는 절차임
- Hold-down Timer: 장애 직후 즉시 재전환하지 않도록 두는 유예 시간임
- Health Check: 장애 여부를 판정하려고 서비스 상태를 검사하는 절차임

## Ⅰ. 개요

- **정의/개념**: 자동 페일오버는 주 노드 장애를 감지해 대기 노드로 서비스를 자동 전환하는 절차이고, 페일백은 복구된 원래 노드로 역할을 다시 되돌려 정상 구조를 회복하는 절차임
- **배경/필요성**: 수동 전환은 판단과 조작 시간이 길어 RTO를 넘기기 쉬우므로, 장애 감지와 승격을 자동화하되 원복 과정은 안정성 검증을 포함해 더 신중하게 설계할 필요가 있음

## Ⅱ. 특징

- 페일오버는 서비스 중단 시간을 줄이는 데 초점을 두므로 빠르고 명확해야 함
- 페일백은 데이터 재동기화와 재장애 위험을 고려해야 하므로 자동화보다 안정성이 더 중요함
- 오탐지와 짧은 네트워크 단절을 장애로 잘못 해석하면 불필요한 전환과 플래핑이 생길 수 있음
- VIP, DNS, 세션, 스토리지 잠금처럼 서비스 소유권을 함께 옮길 수 있어야 실제 전환이 완료됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 페일오버 | 페일백 |
|:---|:---|:---|
| 목적 | 장애 시 서비스를 즉시 계속 제공하는 것이 목적임 | 복구된 원래 구조를 다시 회복하는 것이 목적임 |
| 우선 가치 | 신속성이 가장 중요함 | 안정성과 정합성이 더 중요함 |
| 선행 조건 | 장애 판정, 승격, 트래픽 전환이 필요함 | 데이터 재동기화, 상태 검증, 유예 시간이 필요함 |
| 주요 위험 | 오탐지, Split Brain, 불완전 전환이 위험함 | 재장애, 플래핑, 정합성 미일치가 위험함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 상태 감시기 | 헬스체크와 Heartbeat로 장애 여부를 판정하며 오탐지를 줄일 임계값이 중요함 |
| 역할 전환 장치 | 클러스터 매니저, 로드밸런서, VIP 또는 DNS가 실제 서비스 경로를 새 노드로 돌림 |
| 데이터 동기화 체계 | 복제 지연과 로그 반영 상태를 확인해 승격과 원복의 정합성을 보장함 |
| 복귀 제어 정책 | Hold-down Timer, 수동 승인, 점진 전환으로 재장애를 방지함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장애 감지      | --> | 대기 노드 승격  | --> | 트래픽 전환    | --> | 원복 준비/검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| Health Check 실패 | --> | 서비스 권한 이전 | --> | 데이터 재동기화 | --> | 페일백 여부 결정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **Health Check 실패**: 주 노드 장애를 일정 임계값 이상 확인함
2. **서비스 권한 이전**: 대기 노드를 승격하고 VIP나 라우팅을 새 노드로 전환함
3. **데이터 재동기화**: 복구된 노드와 현재 Active 노드 사이 상태를 다시 맞춤
4. **페일백 여부 결정**: 안정성 검증과 유예 시간 뒤 원래 구조로 되돌릴지 판단함

## Ⅵ. 실무 적용 및 유의점

1. DB와 핵심 상태 저장 시스템은 자동 페일오버가 필요하지만 짧은 네트워크 흔들림에 과민 반응하면 오히려 장애가 커지므로 다단계 상태 점검과 승격 조건을 두고 절체 시간과 오탐 절체 건수로 확인함
2. 페일백은 복구된 노드가 곧바로 다시 장애를 일으킬 수 있으므로 자동 원복을 남용하지 말고 재동기화와 대기 시간을 적용한 뒤 복제 지연과 반복 전환 건수와 원복 성공률로 확인함

## Ⅶ. 결론

자동 페일오버와 페일백의 핵심은 둘 다 빠르게 만드는 데 있지 않고 전환은 신속하게, 원복은 신중하게 분리 설계하는 데 있음.
