# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 암달의 법칙(Amdahl's Law)은 **문제 크기를 고정한 채 코어를 늘릴 때 얻는 속도향상(speedup)이 직렬 비율에 의해 상한에 갇힌다는 법칙**으로, S = 1 / ((1-p) + p/N)로 표현된다.
- **왜 필요한가**: 코어를 N배 늘려도 성능이 N배 오르지 않는 이유를 정량화해, 병렬화 투자 대비 실이득의 한계를 미리 계산하기 위함이다.
- **핵심 직관**: 아무리 사람을 늘려도 "혼자만 해야 하는 일(직렬 부분)"에 걸리는 시간은 줄지 않는다. 그 직렬 시간이 전체를 붙잡아, 코어 무한대에서도 speedup은 1/(1-p)를 못 넘는다.

## 핵심 용어 정리 (내부에 등장하는 것들)

이 법칙은 변수 2개(p, N)짜리 분수식 하나가 핵심이므로, 각 변수와 "고정 문제 크기"라는 전제를 정확히 못 박는 것이 관건이다. 맨 위 상위 키워드가 정체성이다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 암달의 법칙(Amdahl's Law) | 고정 문제에서 speedup = 1/((1-p)+p/N) | 직렬 시간이 전체를 붙잡는 상한 법칙 |
| p (병렬화 가능 비율) | 전체 작업 중 병렬 실행 가능한 시간 비중(0~1) | 90%가 나눠 할 수 있으면 p=0.9 |
| 1-p (직렬 비율) | 순차로만 실행해야 하는 시간 비중 | 반드시 혼자 해야 하는 일 10% |
| N (프로세서 수) | 병렬 실행에 투입한 코어·프로세서 개수 | 8코어면 N=8 |
| speedup S (속도향상) | 1코어 대비 N코어의 실행시간 단축 배수 | 실행시간 100초→25초면 S=4 |
| 강한 확장성(strong scaling) | 문제 크기를 고정하고 코어만 늘리는 관점 | 같은 일을 더 많은 사람이 나눔 |
| 상한 1/(1-p) | N→∞일 때 speedup의 이론 최대값 | p=0.9면 아무리 늘려도 최대 10배 |

## 깊이 이해
- **배경·문제의식**: 1967년 Gene Amdahl이 "직렬 부분이 조금이라도 남으면 병렬화 이득은 곧 포화한다"는 반론으로 제시했다. 프로그램은 결코 100% 병렬화되지 않으며(락·의존성·입출력·초기화), 이 남은 직렬 조각이 전체 성능의 천장을 결정한다는 문제의식이다.
- **작동 원리(어떻게+왜)**: 1코어 실행시간을 1로 두면 직렬 부분 (1-p)는 코어를 늘려도 그대로, 병렬 부분 p만 N으로 나뉘어 p/N이 된다. 따라서 N코어 실행시간은 (1-p)+p/N이고, speedup은 그 역수 1/((1-p)+p/N)이다. N을 무한대로 보내면 p/N→0이 되어 분모에 (1-p)만 남으므로 speedup은 1/(1-p)에 수렴한다 — 직렬 비율이 천장을 정하는 이유다.
- **비유**: 10명이 나눠 할 수 있는 요리(p=0.9)라도, 맨 마지막 "한 명이 간을 보고 플레이팅하는 10%(1-p)"는 사람이 100명이어도 안 줄어든다. 그 마지막 공정 때문에 전체는 절대 10배보다 빨라지지 못한다.
- **구체 예시(워크드)**: p=0.9일 때, N=8이면 speedup = 1/(0.1 + 0.9/8) = 1/(0.1+0.1125) = 1/0.2125 ≈ 4.7배. N=32면 1/(0.1+0.028) = 1/0.128 ≈ 7.8배. N=∞여도 1/0.1 = 10배가 한계다. 코어를 4배(8→32) 늘려도 speedup은 4.7→7.8로 1.7배만 오르는 수확 체감이 드러난다.
- **흔한 오해·주의점**: ① "코어 N배면 N배 빨라진다"는 선형 확장 기대는 직렬 부분을 무시한 오해다. ② p는 "코드 줄 수 비율"이 아니라 "실행시간 비율"이다 — 자주 실행되는 루프의 시간 점유율로 따져야 한다(016 프로파일링). ③ 이 법칙은 문제 크기 고정이 전제이며, 문제가 코어에 맞춰 커지는 상황은 구스타프슨의 법칙(008)이 다룬다.

## 연결 개념
- 구스타프슨의 법칙(008) — 문제 크기가 코어에 맞춰 커질 때의 확장성(scaled speedup)으로 암달의 비관적 상한을 보완
- 프로파일링·핫스팟 분석(016) — 병렬화 비율 p와 직렬 병목 구간을 실측으로 식별
- 병목 분석(004) — 직렬 부분이 곧 성능 천장을 만드는 병목이라는 관점 공유

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 암달의 법칙은 문제 크기 고정 시 speedup = 1/((1-p)+p/N)이며 직렬 비율 (1-p)이 성능 천장을 결정함.
> 2. **가치**: 코어 증설의 수확 체감과 이론 상한 1/(1-p)을 정량화해 병렬화 투자 한계를 사전 판단하게 함.
> 3. **판단 포인트**: 직렬 부분 축소가 코어 증설보다 상한 자체를 끌어올리므로 병목 직렬 구간 제거가 우선임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산식·변수 정의 확인 | S=1/((1-p)+p/N)과 p·N의 의미 | p를 코드 비율로 서술, 변수 혼동 |
| 상한 개념 이해 확인 | N→∞ 시 상한 1/(1-p) 수렴 | 선형 확장 가능으로 단정 |
| 실무 함의 확인 | 직렬 병목 제거 우선·수확 체감 | 코어 증설만 해법으로 제시 |

> 요약: 산식 암기가 아니라 직렬 비율이 만드는 상한과 수확 체감의 실무 함의를 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 문제 크기 고정 시 speedup이 S=1/((1-p)+p/N)로 결정되어 직렬 비율이 상한을 만드는 법칙
- 배경: 1967년 Amdahl이 병렬화 이득이 직렬 부분 때문에 포화함을 지적한 강한 확장성 관점
- 필요성: 코어 증설의 수확 체감과 이론 한계를 미리 계산해 과잉 투자·기대 오류를 막기 위함

---

## Ⅱ. 구조 및 구성요소

- speedup 산출 구조(선형 구조도):

```text
전체 작업 = 직렬 부분(1-p) + 병렬 부분(p)
  -> N코어 실행시간 = (1-p) + p/N
  -> speedup S = 1 / ((1-p) + p/N)
  -> N→∞ 시 상한 = 1/(1-p)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 직렬 부분 (1-p) | N과 무관하게 고정되는 시간 | 상한 1/(1-p)을 결정 |
| 병렬 부분 p | N으로 분할되어 p/N로 축소 | 실행시간 비율로 측정 |
| 프로세서 수 N | 병렬 부분을 나누는 분모 | 늘려도 직렬은 불변 |
| speedup S | 1코어 대비 단축 배수 | N 증가 시 상한에 수렴 |

> 요약: 병렬 부분만 N으로 나뉘고 직렬 부분은 남아, speedup이 1/(1-p)에 갇힘.

---

## Ⅲ. 동작원리 및 흐름도

- speedup 계산·판단 흐름(선형 흐름도):

```text
프로파일링으로 p 측정 -> 목표 코어 수 N 대입
  -> S=1/((1-p)+p/N) 계산 -> 상한 1/(1-p)과 대조
  -> 상한 근접 시 직렬 병목 제거로 방향 전환
```

1. 프로파일러(016)로 자주 실행되는 구간의 시간 점유율을 측정해 병렬화 가능 비율 p를 산정함
2. 투입 예정 코어 수 N을 대입해 speedup S=1/((1-p)+p/N)을 계산함
3. 계산한 S를 이론 상한 1/(1-p)과 비교해 코어 증설의 남은 여지를 판단함
4. S가 상한에 근접하면 코어를 더 늘리는 대신 직렬 부분 (1-p) 자체를 줄이는 개선으로 전환함

---

## Ⅳ. 특징

- 문제 크기를 고정한 강한 확장성 관점으로, 코어를 늘려도 직렬 부분은 줄지 않음
- N→∞에서도 speedup이 1/(1-p)를 못 넘어 병렬화 이득에 명확한 천장이 존재함
- p가 높을수록 상한이 커지므로(예: p=0.95면 상한 20배) 직렬 비율 소폭 개선이 상한을 크게 끌어올림
- 코어를 배로 늘려도 speedup 증가폭은 점점 작아지는 수확 체감이 나타남
- p는 코드 줄 수가 아닌 실행시간 비율이므로 반드시 프로파일링 실측에 근거해야 함

---

## Ⅴ. 심화 비교 및 적용 판단

- 직렬 비율 p에 따른 speedup 비교(같은 코어 수에서 상한이 갈림):

| 구분 | p=0.5 (직렬 50%) | p=0.9 (직렬 10%) | p=0.95 (직렬 5%) |
|:---|:---|:---|:---|
| N=8 speedup | 1/(0.5+0.0625)≈1.8배 | 1/(0.1+0.1125)≈4.7배 | 1/(0.05+0.119)≈5.9배 |
| N→∞ 상한 | 1/0.5 = 2배 | 1/0.1 = 10배 | 1/0.05 = 20배 |
| 실무 함의 | 병렬화 이득 미미 | 코어 증설 효과 뚜렷 | 직렬 제거가 상한 좌우 |

> 요약: 상한을 결정하는 건 코어 수가 아니라 직렬 비율이므로, p를 0.9→0.95로 올리는 개선이 상한을 10→20배로 두 배 키움.

- 리스크와 대응(불릿):
  - 선형 확장 기대 → 코어만 증설하고 성능 정체 → 사전 speedup 계산으로 상한 명시(확인: 계산 S vs 실측 배수)
  - p 과대 추정 → 코드 비율로 p 산정 → 시간 점유율 프로파일링으로 보정(확인: 핫스팟 시간 비중)
  - 직렬 병목 방치 → 상한 근접 후 투자 낭비 → 직렬 구간 알고리즘·락 개선 우선(확인: 상한 대비 speedup 여유)

## Ⅵ. 실무 적용 및 결론

- 적용 방안:
  1. HW 사이징(013) 전 목표 워크로드의 p를 프로파일링으로 실측하고 후보 코어 수별 speedup을 계산해 증설 상한을 근거로 제시함
  2. speedup이 상한 1/(1-p)의 80% 이상에 도달하면 코어 증설을 멈추고 직렬 병목(락 경합·순차 입출력) 제거로 개선 방향을 전환함
  3. 락 프리 자료구조·비동기 입출력·배치 분할로 직렬 비율 (1-p)을 낮춰 상한 자체를 상향함
- 결론:
  - 병렬화 이득은 직렬 비율이 만드는 천장에 갇히므로, 코어 증설과 직렬 제거를 상한 계산으로 저울질해야 함
  - 문제 크기가 코어에 맞춰 커지는 대규모 워크로드는 암달의 비관적 상한 대신 구스타프슨 관점(008)으로 재평가 필요
