## Ⅰ. 개요
- **정의**: 이미지, 동영상 등의 정적/동적 콘텐츠를 사용자와 지리적으로 가까운 분산 서버(Edge)에 캐싱하여 빠르게 전송하는 네트워크 구조임.
- **배경/필요성**: 단일 원본(Origin) 서버에 트래픽이 집중될 때 발생하는 병목, 장애 및 글로벌 사용자의 응답 지연(Latency) 문제 해결.
- **출제 의도**: CDN의 기본 동작 절차, DNS(GSLB)와의 연동 원리, 캐시 무효화 및 동적 트래픽 최적화 방식 이해.

## Ⅱ. 구성요소
```text
+-------------+         (Cache Miss)         +-------------+
| Origin Server|<--------------------------->| Edge Server |
| (원본 데이터) |                            | (캐시 데이터) |
+-------------+                              +-------------+
                                                    ^
            +-------------+                         |
            | GSLB / DNS  |----------------->  [User Client]
            | (최적 경로)   |  (IP 응답)         (웹 브라우저)
            +-------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Origin Server | 모든 원본 데이터가 최초로 생성되고 저장되는 메인 서버 시스템 | 본사 물류창고 |
| Edge Server | 전 세계 지역별(PoP)로 배치되어 원본 데이터를 캐싱하고 사용자에게 직접 서비스 | 지역 대리점 |
| GSLB (DNS) | 사용자의 위치나 에지 서버의 부하 상태를 파악해 최적의 에지 서버 IP를 반환 | 내비게이션 안내 |
> 요약: GSLB가 사용자를 가장 가까운 에지 서버로 안내하고, 에지 서버가 캐싱된 원본을 대신 응답함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 사용자 요청|-> | GSLB 라우팅 |-> | 캐시 확인   |-> | 원본 질의 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **사용자 요청**: 클라이언트가 브라우저에 URL을 입력하여 콘텐츠(예: 이미지) 다운로드를 요청함.
2. **GSLB 라우팅**: DNS 질의 과정에서 GSLB가 사용자 위치를 파악하여 가장 빠르고 부하가 적은 Edge 서버 IP를 반환함.
3. **캐시 확인**: 사용자가 Edge 서버에 접속하면, 서버는 요청된 콘텐츠가 자신의 캐시에 있는지(Cache Hit) 확인함.
4. **원본 질의**: 캐시에 데이터가 없거나 만료된 경우(Cache Miss), Edge 서버가 Origin 서버에서 데이터를 가져와 캐싱한 후 사용자에게 전달함.
> 요약: 지능적인 DNS 라우팅과 지역별 캐싱을 통해 원본 서버 개입을 최소화하는 전송 체계임.

## Ⅳ. 문제점
- **캐시 갱신 지연(Stale Data)**: 원본 데이터가 변경되었으나 Edge 캐시가 갱신되지 않아 사용자가 과거 데이터를 보게 됨.
- **동적 콘텐츠 한계**: 사용자 맞춤형 데이터(API 응답 등)는 캐싱이 불가능해 여전히 Origin 서버 부하 유발.
- **운영 비용 증가**: 트래픽 증가에 비례하여 CDN 서비스 업체에 지불해야 하는 데이터 전송(Egress) 비용 부담.

## Ⅴ. 개선방안
- **TTL 최적화**: 콘텐츠 특성에 맞게 캐시 유지 시간(TTL)을 조정하고 즉각적인 캐시 무효화(Purge) API 연동 (단기).
- **동적 가속 적용**: DSA(Dynamic Site Acceleration) 기술을 통해 동적 트래픽의 라우팅 경로와 TCP 세션 최적화 (중기).
- **엣지 컴퓨팅 융합**: 단순 캐싱을 넘어 Lambda@Edge 등 서버리스 함수를 에지에 배치하여 사용자 인근에서 연산 처리 (장기).

## Ⅵ. 전망
- 글로벌 OTT, 게임, 클라우드 환경의 성장으로 트래픽의 대다수가 CDN을 통해 유통되는 추세가 심화될 것임.
- 콘텐츠 전송뿐만 아니라 WAF, DDoS 방어 등 엣지 보안(Security at the Edge) 기능과 결합한 통합 플랫폼으로 진화 중임.
