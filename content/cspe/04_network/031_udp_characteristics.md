## 미리 알고가기

- 데이터그램: 메시지 경계를 유지한 채 독립적으로 전달되는 전송 단위임
- 체크섬: 전송 중 비트 오류를 검출하는 값임
- 비연결형: 송수신자가 사전 연결 절차 없이 바로 데이터를 보내는 방식임
- 증폭 공격: 작은 요청으로 큰 응답을 유도해 피해자에게 트래픽을 몰아주는 공격임

## Ⅰ. 개요

- **정의/개념**: UDP는 연결 수립과 재전송, 순서 보장 기능을 두지 않고 포트 다중화와 체크섬만 제공하는 단순한 전송 계층 프로토콜임. 애플리케이션은 이 위에서 필요한 신뢰성과 제어 기능을 직접 추가할 수 있음
- **배경/필요성**: 실시간 미디어, 게임, 단발성 질의 응답은 연결 수립과 전송 계층 재전송을 생략하고 애플리케이션에서 손실 대응 범위를 정할 필요가 있음

## Ⅱ. 특징

- 헤더가 8바이트로 작고 연결 수립 절차가 없어 지연과 오버헤드가 낮음
- 메시지 경계를 그대로 유지하므로 응용 프로그램이 요청과 응답 단위를 다루기 쉬움
- 순서 보장과 재전송이 없으므로 손실과 역전이 생기면 애플리케이션이 직접 처리해야 함
- 발신지 위조가 상대적으로 쉬워 증폭 공격과 반사 공격의 통로로 악용될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | TCP | UDP |
|:---|:---|:---|
| 연결 방식 | 연결을 먼저 수립한 뒤 데이터를 보냄 | 연결 절차 없이 데이터그램을 바로 보냄 |
| 전송 보장 | 순서 보장과 재전송을 제공함 | 전달 보장과 순서 보장을 기본 제공하지 않음 |
| 오버헤드 | 제어 기능이 많아 지연과 상태 관리 비용이 큼 | 헤더와 상태 관리가 단순해 지연이 작음 |
| 적합한 서비스 | 파일 전송, 웹, 데이터베이스처럼 무결성이 중요한 서비스에 적합함 | DNS, 음성, 게임, 스트리밍처럼 실시간성이 중요한 서비스에 적합함 |

> 요약: UDP는 기능이 적어서 약한 것이 아니라, 지연을 줄이기 위해 필요한 기능만 남긴 전송 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Source Port | 송신 애플리케이션을 구분하며 응답이 돌아올 위치를 나타냄 |
| Destination Port | 수신 측에서 어떤 서비스가 데이터를 받아야 하는지 식별함 |
| Length | UDP 헤더와 데이터그램 전체 길이를 나타냄 |
| Checksum | 헤더와 데이터가 전송 중 손상됐는지 확인하며 오류가 있으면 보통 폐기함 |

```text
+---------------+---------------+
| Source Port   | Dest Port     |
+---------------+---------------+
| Length        | Checksum      |
+---------------+---------------+
| Data                          |
+-------------------------------+
```

> 요약: UDP는 포트 식별과 오류 검출만 제공하고, 나머지 신뢰성은 애플리케이션에 맡기는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 데이터생성 | --> | 헤더부착  | --> | 즉시전송  | --> | 앱단처리  |
+----------+     +----------+     +----------+     +----------+
```

1. **데이터생성**: 애플리케이션이 보낼 메시지를 만듦
2. **헤더부착**: OS가 포트와 길이, 체크섬을 붙여 UDP 데이터그램을 만듦
3. **데이터그램전송**: 연결 확인 없이 UDP 데이터그램을 IP 계층에 넘김
4. **앱단처리**: 수신 애플리케이션이 손실과 순서 문제를 필요하면 자체적으로 보완함

## Ⅵ. 실무 적용 및 유의점

1. DNS나 실시간 미디어처럼 연결 수립을 생략해야 하는 서비스에서는 UDP를 적용하되 손실과 순서 뒤바뀜을 감안해 애플리케이션 타임아웃과 재시도 정책을 설계하고 지연 시간과 손실률로 확인함
2. 공개 UDP 서비스는 반사·증폭 공격의 통로가 되기 쉬우므로 소스 검증과 비율 제한을 함께 적용하고 초당 요청 수와 비정상 응답 증폭 비율로 확인함

## Ⅶ. 결론

UDP의 핵심은 기능을 많이 제공하는 데 있지 않고, 지연을 최소화한 빈 전송 기반 위에 필요한 제어를 서비스 특성에 맞게 올릴 수 있게 하는 데 있음.
