## Ⅰ. 개요
- **정의**: 퍼블릭 클라우드 환경에서 테넌트별로 안전하게 격리된 가상 네트워크를 구성하고, 자원 간 통신을 제어하는 인프라 구조임.
- **배경/필요성**: 멀티 테넌트 환경에서의 보안(격리) 필수, 유연한 서브넷 구성 및 외부(인터넷, 온프레미스)와의 연결성 확보.
- **출제 의도**: VPC, Subnet, 라우팅, 보안그룹 등 클라우드 네트워킹 핵심 구성요소의 역할과 구성 방식 이해.

## Ⅱ. 구성요소
```text
+---------------------------------------------------+
|               VPC (Virtual Private Cloud)         |
|  +-----------------+         +-----------------+  |
|  | Public Subnet   |         | Private Subnet  |  |
|  | [Web Server]    |         | [DB Server]     |  |
|  +-----------------+         +-----------------+  |
|          |                            |           |
|    [Internet GW]                [NAT GW]          |
+----------|----------------------------|-----------+
           v                            v
       인터넷 (Internet)          아웃바운드 인터넷
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| VPC | 사용자 전용의 논리적으로 격리된 프라이빗 가상 네트워크 공간 | 독립된 사유지 |
| Subnet | VPC 내의 IP 대역을 분할한 네트워크 조각 (퍼블릭/프라이빗) | 사유지 내 건물 구역 |
| Security Group | 인스턴스 수준에서 인바운드/아웃바운드 트래픽을 제어하는 가상 방화벽 | 개별 건물의 경비원 |
> 요약: 클라우드 네트워크는 VPC라는 큰 울타리 안에 서브넷을 나누고 라우터와 게이트웨이로 트래픽 흐름을 통제함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| VPC 생성  |-> | 서브넷 구성 |-> | 라우팅 설정 |-> | 보안/배포 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **VPC 생성**: 클라우드 리전 내에 사용하고자 하는 큰 범위의 IP CIDR 블록을 지정하여 VPC를 생성함.
2. **서브넷 구성**: 서비스 목적에 맞게 VPC를 퍼블릭(외부 접근 허용)과 프라이빗(내부 통신 전용) 서브넷으로 분할함.
3. **라우팅 설정**: 인터넷 게이트웨이(IGW) 또는 NAT 게이트웨이를 생성하고 라우팅 테이블을 통해 트래픽 경로를 지정함.
4. **보안/배포**: 보안 그룹(Security Group) 및 NACL(Network ACL)을 설정한 후 자원(VM, RDS)을 배치함.
> 요약: 네트워크 기초 공사부터 경로 설정, 방화벽 룰 적용 순으로 인프라 환경을 단계적 프로비저닝함.

## Ⅳ. 문제점
- **아키텍처 복잡도**: 멀티 리전, 멀티 클라우드 사용 시 네트워크 피어링 및 라우팅 설정이 매우 복잡해짐.
- **트래픽 요금 과다**: 클라우드 외부로 나가는 데이터 전송(Egress) 및 NAT 게이트웨이 트래픽 요금이 가중됨.
- **설정 휴먼 에러**: 보안 그룹 포트 오픈 실수나 라우팅 오류로 인한 심각한 데이터 유출 및 서비스 장애 발생 위험.

## Ⅴ. 개선방안
- **자동화 적용**: Terraform, AWS CloudFormation 등 코드 기반 인프라(IaC)를 통해 설정 표준화 및 오류 방지 (단기).
- **허브 앤 스포크**: Transit Gateway 등을 활용하여 다수 VPC 및 온프레미스 연결을 중앙 집중형으로 최적화 (중기).
- **멀티 클라우드 연동**: 클라우드 네이티브 라우팅 플랫폼을 도입하여 하이브리드/멀티 클라우드 간 일관된 통신망 구축 (장기).

## Ⅵ. 전망
- 엔터프라이즈의 하이브리드 클라우드 확장에 따라 소프트웨어 정의 클라우드 네트워킹(SDCN) 기술이 더욱 중요해질 것임.
- 서브넷 단위 관리를 넘어, 컨테이너 환경을 위한 CNI(Container Network Interface) 연동 중심 아키텍처로 무게 중심이 이동 중임.
