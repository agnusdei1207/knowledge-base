## Ⅰ. 개요
- **정의**: 문자열 기반의 도메인 이름(example.com)을 시스템이 처리할 수 있는 IP 주소로 변환하는 분산 데이터베이스임.
- **배경 및 필요성**: 숫자 IP를 외우기 어려운 문제를 해결하고, IP가 변경되더라도 서비스 주소의 연속성을 보장하기 위함.
- **출제 의도**: 계층형 네임스페이스 탐색 구조 및 다중 리졸빙 절차, 도메인 레코드의 활용 방안 이해 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **Root/TLD 서버** | 도메인 트리의 최상위 영역(.com, .kr)을 관장하여 하위 네임 서버를 안내 | 대형 도서관의 구역별 색인 분류함 |
| **재귀적 리졸버** | 사용자 PC를 대신하여 여러 네임 서버를 계층적으로 묻고 다녀 IP를 찾음 | 서고에서 원하는 책을 찾아주는 사서 |
| **DNS 레코드** | 도메인에 매핑된 실제 데이터 유형 (A, AAAA, CNAME, MX 등) | 도서 검색 카드에 적힌 실제 위치 정보 |

> 요약: DNS는 분산된 네임 서버들을 계층적으로 거슬러 올라가며 도메인과 IP의 레코드 매핑을 찾아냄.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **캐시 검색**: PC 웹 브라우저가 자체 DNS 캐시나 hosts 파일을 먼저 탐색함.
2. **리졸버 질의 (재귀적)**: 로컬 캐시에 없으면 통신사 등이 운영하는 재귀적 DNS 리졸버에 변환을 요청함.
3. **계층 탐색 (반복적)**: 리졸버가 최상위 Root 서버부터 TLD, 최종 권한(Authoritative) 서버 순서로 반복 질의함.
4. **응답 및 캐싱 반환**: 획득한 목적지 A 레코드 IP를 리졸버가 저장(캐싱)한 뒤 PC에 결과 반환함.

> 요약: 사용자 캐시 확인 후, 리졸버 서버가 상위 계층부터 하향식 질의를 통해 최종 IP를 획득 및 반환함.

## Ⅳ. 문제점
- DNS 캐시 포이즈닝 해킹 (원인: 리졸버가 응답을 기다릴 때 해커가 위조 IP를 먼저 보내 악성 캐시를 저장시킴)
- 단일 지점 장애(SPOF) 리스크 (원인: 권한 서버 1대 다운 시 해당 도메인에 연계된 모든 인프라 접속 불가)
- 질의 평문 노출에 따른 프라이버시 침해 (원인: 브라우징하는 웹사이트 도메인이 ISP 등에 감청/노출 가능함)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 도메인 권한 서버 분산 다중화 (Master-Slave로 DNS 팜을 구성하여 장애 시 가용성과 안정성 보장)
- **중기 방안**: [중기] DNSSEC(보안 확장 표준) 적용 (DNS 응답 패킷에 전자서명을 추가해 데이터 위/변조 가능성 원천 차단)
- **장기 방안**: [장기] 암호화 DNS 터널링(DoH/DoT) 도입 (DNS 질의 통신 자체를 TLS 암호화 채널을 태워 전송 내용 노출 방지)

## Ⅵ. 전망
- 글로벌 엣지 인프라 중심의 Anycast DNS와 무중단 트래픽 라우팅을 돕는 지능적 제어 시스템으로 고도화 중임.
