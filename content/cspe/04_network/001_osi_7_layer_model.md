# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 통신이 일어나는 과정을 7단계로 나눈 국제 표준 모델
- **왜 필요한가**: 과거 장비 벤더마다 독자 프로토콜을 사용하여 호환이 안 되던 문제를 해결하기 위함
- **핵심 직관**: 편지를 써서(7) 봉투에 넣고(6, 5) 우체국을 거쳐(4, 3) 트럭으로 배송(2, 1)하는 과정과 같다.

## 깊이 이해
- **배경·문제의식**: IBM의 SNA 등 벤더 종속적 통신 구조로 인해 이기종 간 통신이 불가능했다. ISO가 이기종 간 호환성을 위해 개방형 시스템 간 상호 접속 표준(OSI)을 제정했다.
- **작동 원리**: 송신 측은 7계층부터 1계층까지 데이터를 캡슐화(헤더 추가)하여 전송하고, 수신 측은 1계층부터 7계층까지 역캡슐화(헤더 제거)하여 데이터를 복원한다.
- **비유**: 회사의 사장(7계층 응용)이 지시를 내리면, 비서(6계층 표현)가 문서를 번역하고, 부서장(5계층 세션)이 회의를 조율하며, 우체국(4계층 전송, 3계층 네트워크)을 통해 배달하는 식.
- **구체 예시**: 웹 브라우저(L7 HTTP)에서 요청을 암호화(L6 TLS)하고 포트 연결(L5, L4 TCP) 후, IP 주소(L3)와 MAC 주소(L2)를 붙여 랜선(L1 전기 신호)으로 보낸다.
- **흔한 오해·주의점**: 실제 인터넷은 OSI 7계층이 아닌 TCP/IP 4계층으로 동작한다. OSI는 통신 과정을 분석하고 교육, 트러블슈팅을 위한 참조 모델(Reference Model)로 주로 쓰인다.

## 연결 개념
- TCP/IP 4계층 모델 — 실제 인터넷의 사실상(De facto) 표준
- 캡슐화(Encapsulation) — 각 계층을 지날 때 헤더가 추가되는 과정
- PDU(Protocol Data Unit) — 계층별 데이터 처리 단위 (Data, Segment, Packet, Frame, Bit)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OSI 7계층 모델은 이기종 시스템 간 통신을 위해 ISO가 제정한 7단계 네트워크 참조 표준 모델이다.
> 2. **가치**: 통신 과정을 모듈화하여 계층 간 독립성을 보장하고, 네트워크 장애 발생 시 문제 원인을 특정(Troubleshooting)하기 쉽다.
> 3. **판단 포인트**: 각 계층의 PDU, 주요 장비, 대표 프로토콜을 정확히 매핑하여 설계와 운영의 기준으로 삼아야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층별 역할과 PDU에 대한 정확한 이해 | 계층명, PDU(Bit, Frame, Packet, Segment), 대표 장비 연결 | 계층 순서를 틀리거나 L2/L3 장비 혼동 |
| 캡슐화·역캡슐화 메커니즘 이해 | 송신 측 헤더 부착(캡슐화), 수신 측 헤더 제거(역캡슐화) | 흐름 설명 없이 계층만 나열 |
| 네트워크 트러블슈팅 적용 역량 | Ping(L3), ARP(L2), Port(L4) 기반 장애 구간 특정 | "호환성이 좋다" 등 빈 추상 표현 남발 |

> 요약: OSI 7계층은 단순 암기가 아니라, 네트워크 설계 및 장애 처리 시 계층적 접근을 위한 분석 도구로써 활용된다.

---

## Ⅰ. 개요 및 필요성

- 정의: 이기종 컴퓨터 상호 통신을 위해 ISO가 제정한 7단계 네트워크 통신 참조 모델
- 배경: 과거 벤더 종속적 통신 규격(SNA 등)으로 인해 장비 간 상호 연동이 불가능
- 필요성: 모듈화를 통해 계층 간 독립성을 보장하고 네트워크 장애 원인을 신속히 격리·식별하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
Sender (캡슐화)                    Receiver (역캡슐화)
응용(L7) -> Data                    Data <- 응용(L7)
표현(L6) -> Data                    Data <- 표현(L6)
세션(L5) -> Data                    Data <- 세션(L5)
전송(L4) -> Segment                 Segment <- 전송(L4)
네트워크(L3) -> Packet              Packet <- 네트워크(L3)
데이터링크(L2) -> Frame             Frame <- 데이터링크(L2)
물리(L1) -> Bit (전기 신호) -------> Bit <- 물리(L1)
```

| 계층 | PDU | 주요 역할 및 프로토콜 | 장비 |
|:---|:---|:---|:---|
| L7 응용 (Application) | Data | 사용자 인터페이스 제공 (HTTP, FTP, SMTP) | L7 스위치, WAF |
| L6 표현 (Presentation) | Data | 데이터 포맷 변환, 암호화, 압축 (JPEG, TLS) | - |
| L5 세션 (Session) | Data | 논리적 연결 성립·유지·동기화 (RPC, NetBIOS) | - |
| L4 전송 (Transport) | Segment | 종단 간(End-to-End) 신뢰성 보장 (TCP, UDP) | L4 스위치 |
| L3 네트워크 (Network) | Packet | 최적 경로 설정(Routing), 논리 주소 지정 (IP, ICMP) | 라우터, L3 스위치 |
| L2 데이터링크 (Data Link) | Frame | 노드 간(Node-to-Node) 오류 제어, MAC 주소 (Ethernet) | 스위치, 브릿지 |
| L1 물리 (Physical) | Bit | 전기적·기계적 신호 변환 및 전송 (RS-232C, 케이블) | 허브, 리피터 |

> 요약: OSI 모델은 L1~L3의 하위 계층(네트워크 지원)과 L5~L7의 상위 계층(사용자 지원), 그 사이를 연결하는 L4(전송)로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 요청(Data) -> L4 포트 부착(Segment) -> L3 IP 부착(Packet) -> L2 MAC 부착(Frame) -> 전기 신호(Bit) 전송
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | **데이터 생성 (L7~L5)** | 사용자 요청 데이터를 응용 프로토콜 형식으로 포맷팅 및 암호화 |
| 2 | **포트 할당 및 분할 (L4)** | 송수신 포트 번호 부착, 세그먼트 단위로 분할하여 오류 복구 체계 마련 |
| 3 | **라우팅 주소 지정 (L3)** | 목적지 IP 주소 부착, 최적 경로 테이블 참조 (라우팅) |
| 4 | **프레이밍 및 전송 (L2~L1)** | 인접 노드 MAC 주소 부착(FCS 포함), 비트 스트림으로 물리 매체 전송 |

> 요약: 송신자는 데이터에 각 계층의 제어 정보(Header)를 덧붙이는 캡슐화를, 수신자는 이를 벗겨내는 역캡슐화를 수행한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 계층 독립성 | 한 계층의 변경이 다른 계층에 영향을 주지 않음 | 인터페이스 표준화로 벤더 종속성 탈피 |
| 표준 참조성 | 실제 구현보다 통신 구조 설계 및 분석의 기준 제공 | 실제 인터넷 표준은 TCP/IP가 장악 (De facto) |
| 오버헤드 | 데이터 전송 시 각 계층마다 헤더가 추가됨 | 페이로드 대비 제어 정보 비율(MTU 1500바이트 기준) |

> 요약: OSI 모델은 엄격한 모듈화로 상호 운용성을 확보했으나, 구현 복잡도로 인해 실제 시장에서는 TCP/IP에 주도권을 내주었다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | OSI 7계층 | TCP/IP 4계층 | 선택 기준 |
|:---|:---|:---|:---|
| 목적 | 이기종 통신 표준 제정 (국제 표준, De jure) | 인터넷 통신 실용화 (사실상 표준, De facto) | 표준화 문서 vs 실제 구현 |
| 계층 구조 | 7계층 (응용/표현/세션 분리) | 4계층 (응용으로 통합) | 세밀한 기능 분류 vs 빠른 처리 속도 |
| 통신 방식 | 연결형 및 비연결형 모두 지원 | 네트워크 계층은 비연결형(IP)만 지원 | 통신 신뢰성의 주체(L4 vs L3) |

> 요약: OSI 모델은 네트워크 구조를 이해하고 설계하는 '개념적 뼈대'로, TCP/IP는 실제 서비스를 구동하는 '구현체'로 활용된다.

| 리스크 (장애) | 원인 특정 위치 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| L1/L2 장애 | 케이블 단선, MAC 플래핑 | 케이블 교체, 스위치 포트 상태 확인 | Link LED, 포트 Error 카운트 |
| L3 장애 | 라우팅 루프, 잘못된 서브넷 | Ping, Traceroute로 단절 구간 식별 | ICMP 응답률, TTL 초과 로그 |
| L4/L7 장애 | 포트 차단, 서버 프로세스 다운 | Telnet 포트 확인, WAF/방화벽 정책 검토 | TCP SYN Timeout, HTTP 50x 에러 |

> 요약: 네트워크 장애 발생 시 하위 계층(L1)부터 상위 계층(L7)으로 순차적 점검(Bottom-Up 방식)을 수행하여 병목을 격리한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **장애 트러블슈팅 자동화**: NMS(Network Management System)에서 L1(물리 링크)부터 L4(포트 연결)까지 상태 지표를 수집하여 장애 구간을 자동 격리
2. **보안 아키텍처 설계**: L3/L4 방화벽(IP/Port 제어)과 L7 WAF(Web Application Firewall, 페이로드 검사)를 분리 배치하여 심층 방어(Defense in Depth) 구성
3. **네트워크 가상화(SDN)**: L2/L3 제어 평면을 분리하여 스위치(L2)와 라우터(L3)의 데이터 평면을 중앙 컨트롤러에서 통합 프로비저닝

**결론 (2줄):**
- 기술사 판단: OSI 7계층은 실제 구현 프로토콜은 아니나, 클라우드 및 SDN 아키텍처에서 계층별 결합도를 낮추고 모듈 간 인터페이스를 설계하는 불변의 기준이다.
- 향후 방향: 최근 마이크로서비스 및 서비스 메시 환경에서는 L4/L7 로드밸런싱 경계가 모호해지며, 응용 계층 중심의 가시성 확보가 더욱 중요해지고 있다.
