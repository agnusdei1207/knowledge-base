## 미리 알고가기

- PDU: 각 계층이 다루는 데이터 단위이며 계층별 헤더 해석 기준이 됨
- 캡슐화: 상위 데이터에 하위 계층 제어 정보를 붙여 전송 단위로 만드는 과정임
- 역캡슐화: 수신 측이 계층별 헤더를 제거하며 상위 계층으로 데이터를 넘기는 과정임
- 계층 인터페이스: 상위 계층이 하위 계층의 구현 세부를 모르고 서비스를 쓰게 하는 경계임

## Ⅰ. 개요

- **정의/개념**: OSI 7계층 모델은 네트워크 통신 기능을 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 계층으로 나눠 설명하는 참조 모델임
- **배경/필요성**: 제조사와 프로토콜이 달라도 장애 위치, 기능 책임, 표준 인터페이스를 같은 기준으로 설명하려면 계층화된 참조 구조가 필요함

## Ⅱ. 특징

- 각 계층은 바로 아래 계층 서비스를 이용하고 바로 위 계층에 서비스를 제공함
- 계층별 PDU와 주소 체계가 달라 링크·경로·세션·응용 장애를 계층별로 구분할 수 있음
- 캡슐화와 역캡슐화로 송수신 양 끝의 같은 계층이 논리적으로 대응함
- 실제 인터넷 구현은 TCP/IP가 중심이지만 OSI는 설명, 비교, 진단 기준으로 쓰임

## Ⅲ. 종류 및 비교

| 판단 기준 | OSI 7계층 | TCP/IP 4계층 |
|:---|:---|:---|
| 성격 | 통신 기능을 세분화한 참조 모델임 | 인터넷 프로토콜 구현을 묶은 실무 모델임 |
| 계층 구분 | 세션, 표현, 응용을 별도 계층으로 구분함 | 응용 계층에서 세 기능을 함께 다룸 |
| 설명 강점 | 장애 위치와 장비 역할을 계층별로 설명하기 쉬움 | 실제 프로토콜 배치와 서비스 구현을 설명하기 쉬움 |
| 주의점 | 실제 프로토콜이 항상 7계층에 정확히 맞지는 않음 | 세부 기능 책임을 설명할 때 계층 경계가 거칠 수 있음 |

> 요약: OSI는 기능 책임을 세밀하게 나누는 설명 기준이고, TCP/IP는 인터넷 구현을 설명하는 기준임

## Ⅳ. 구성요소 및 구조

| 계층 | 설명 |
|:---|:---|
| 7 응용 | 사용자가 접하는 네트워크 서비스와 응용 프로토콜을 제공함 |
| 6 표현 | 데이터 형식 변환, 압축, 암복호화 표현 처리를 담당함 |
| 5 세션 | 통신 세션의 시작, 유지, 종료와 동기화 지점을 관리함 |
| 4 전송 | 포트 기반 종단 간 전송, 순서, 흐름, 혼잡 제어를 담당함 |
| 3 네트워크 | IP 주소와 라우팅으로 다른 네트워크까지 패킷을 전달함 |
| 2 데이터링크 | MAC 주소와 프레임으로 같은 링크 안의 노드 간 전달을 처리함 |
| 1 물리 | 비트를 전기, 광, 무선 신호로 바꿔 매체에 실어 보냄 |

```text
-----------+  Data
|  L7~L5   |
+-----------+  Segment
|  L4       |
+-----------+  Packet
|  L3       |
+-----------+  Frame
|  L2       |
+-----------+  Bit
|  L1       |
+-----------+
```

> 요약: OSI 구조는 서비스, 종단 전송, 경로 선택, 링크 전달, 물리 신호를 단계별 책임으로 분리함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 응용데이터 | --> | 캡슐화   | --> | 물리전송  | --> | 역캡슐화 |
+----------+     +----------+     +----------+     +----------+
```

1. **응용데이터**: 송신 측 응용 계층이 전송할 데이터를 생성함
2. **캡슐화**: 각 하위 계층이 주소, 제어, 오류 검사용 정보를 붙임
3. **물리전송**: 프레임과 비트가 링크와 장비를 거쳐 목적지로 이동함
4. **역캡슐화**: 수신 측이 계층별 정보를 해석하고 상위 계층으로 넘김

## Ⅵ. 실무 적용 및 유의점

1. 장애 분석에서는 물리 링크, MAC 학습, IP 라우팅, 포트 연결, 응용 응답을 순서대로 확인해야 하며 각 단계의 링크 상태, ARP, 라우팅 테이블, 세션 로그로 원인을 좁힘
2. 보안 설계에서는 L3/L4 방화벽과 L7 WAF처럼 통제 위치가 다르므로 차단 기준을 계층별로 분리하고 정책 적중 로그와 우회 트래픽으로 확인함

## Ⅶ. 결론

OSI 7계층은 실제 구현 그 자체가 아니라 통신 기능의 책임과 장애 위치를 계층별로 설명하게 해 주는 기준임.

## 작성 근거(검토용)

- OSI의 답안 판단 축은 "구현 제품"이 아니라 계층별 책임 분리이므로 정의, 특징, 구조를 모두 기능 책임 중심으로 배치함
- TCP/IP와의 비교는 속도나 우열이 아니라 참조 모델과 구현 모델의 설명 범위 차이를 보이도록 구성함
- 결론은 장애 분석과 책임 분리라는 실제 답안 역할을 회수함
