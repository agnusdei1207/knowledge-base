# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: OSI 7계층 모델은 이기종 시스템 간 통신 과정을 기능별 7개 **계층(Layer)**으로 나눈 국제표준 **참조 모델(Reference Model)**이다.
- **왜 필요한가**: 과거 IBM SNA 등 벤더마다 독자 통신 규격을 써서 다른 회사 장비끼리 대화가 안 되던 문제를, 통신 기능을 표준 계층으로 쪼개 해결하기 위함이다.
- **핵심 직관**: 편지를 쓰고(L7~L5) → 봉투에 주소·등기 여부를 적고(L4~L3) → 우체통·트럭으로 배송(L2~L1)하는 과정처럼, 통신을 "역할이 다른 7개 담당자의 릴레이"로 본 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 표의 용어는 답안용에 그대로 등장하므로, 여기서 비유와 함께 먼저 이해하고 넘어간다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 참조 모델 (Reference Model) | 실제 구현 규격이 아니라, 통신 구조를 이해·설계·분석하기 위한 개념적 뼈대 | 실제 건물이 아니라 건축 도면. 도면 자체가 벽돌은 아니지만 모든 시공의 기준이 됨 |
| 계층화 (Layering) | 통신 기능을 독립된 계층으로 나누고, 각 계층은 바로 위·아래 계층하고만 정해진 규칙으로 대화 | 회사 조직도. 사원이 사장에게 직접 안 가고 팀장→부장 순으로 보고 |
| 캡슐화 (Encapsulation) | 송신 시 상위 계층 데이터에 각 계층이 자기 제어정보(헤더)를 앞에 덧붙이는 것 | 편지를 봉투에 넣고, 그 봉투를 다시 소포 상자에 넣는 것 |
| 역캡슐화 (Decapsulation) | 수신 시 하위 계층부터 자기 계층 헤더를 벗겨 원래 데이터를 복원하는 것 | 소포 상자를 뜯고, 안의 봉투를 열어 편지를 꺼내는 것 |
| 헤더 (Header) | 각 계층이 붙이는 제어정보(주소·순서·오류검출 등)로, 데이터 앞에 위치 | 택배 송장. 내용물(데이터)이 아니라 배송에 필요한 정보 |
| PDU (Protocol Data Unit) | 각 계층에서 처리하는 데이터 단위의 통칭. 계층마다 이름이 다름 | 같은 화물을 낱개→상자→팔레트→컨테이너로 부르는 단위 차이 |
| 비트 (Bit, L1 PDU) | 물리 계층이 다루는 0·1 전기/광 신호 | 모스 부호의 점·선 |
| 프레임 (Frame, L2 PDU) | MAC 주소가 붙은, 인접 노드 간 전송 단위 | 옆집까지 전달할 손편지 봉투 |
| 패킷 (Packet, L3 PDU) | IP 주소가 붙은, 목적지까지 경로를 찾아가는 단위 | 최종 도시 주소가 적힌 소포 |
| 세그먼트 (Segment, L4 PDU) | 포트 번호·순서번호가 붙은, 종단 간 신뢰성 처리 단위 | 등기 번호가 매겨진 우편물 |
| MAC 주소 | 랜카드에 고정된 48비트 물리 주소. 인접 노드 식별용 (L2) | 사람의 지문(변하지 않는 고유 번호) |
| IP 주소 | 네트워크상 위치를 나타내는 논리 주소. 목적지 식별·라우팅용 (L3) | 집 주소(이사 가면 바뀜) |
| 포트 번호 | 한 호스트 안에서 어느 프로그램(프로세스)인지 구분하는 16비트 번호 (L4) | 아파트 동은 같아도 다른 호수 |
| De jure / De facto | 법적·공식 표준(De jure) vs 시장이 실제 채택한 사실상 표준(De facto) | 표준어 규정(De jure) vs 실제 많이 쓰는 말(De facto) |

## 깊이 이해
- **배경·문제의식**: 1970년대에는 IBM SNA, DEC DECnet 등 벤더마다 통신 규격이 달라 이기종 장비 간 연결 자체가 불가능했다. ISO는 "개방형 시스템 상호접속(Open Systems Interconnection)"을 목표로, 어느 벤더든 같은 규칙을 따르면 통신되도록 1984년 7계층 참조 모델(ISO 7498)을 제정했다.
- **작동 원리(어떻게+왜)**: 통신 기능을 7개로 쪼갠 뒤, 각 계층은 오직 바로 위·아래 계층하고만 약속된 인터페이스로 대화한다. 이렇게 하면 한 계층 내부 구현(예: 유선→무선)을 바꿔도 다른 계층은 영향을 받지 않는다(계층 독립성). 송신 측은 L7→L1로 내려가며 각 계층이 헤더를 덧붙이고(캡슐화), 수신 측은 L1→L7로 올라가며 자기 헤더를 벗긴다(역캡슐화). 대칭 구조라 양쪽 같은 계층끼리 "논리적으로 직접 대화"하는 것처럼 보인다.
- **7계층의 역할**:
  - L7 응용(Application): 사용자·프로그램이 직접 쓰는 통신 서비스 (HTTP, FTP, SMTP)
  - L6 표현(Presentation): 데이터 표현 방식 통일 — 인코딩·압축·암호화 (JPEG, TLS 암호화)
  - L5 세션(Session): 대화(세션)의 시작·유지·종료와 동기화 (RPC, 인증 세션)
  - L4 전송(Transport): 종단 간(End-to-End) 신뢰성·순서·흐름 제어 (TCP, UDP)
  - L3 네트워크(Network): 여러 네트워크를 건너 목적지까지 최적 경로 결정 (IP, 라우팅)
  - L2 데이터링크(Data Link): 같은 링크의 인접 노드 간 오류 제어·MAC 주소 지정 (Ethernet)
  - L1 물리(Physical): 비트를 전기·광·전파 신호로 바꿔 매체에 실어보냄 (케이블, RS-232C)
- **비유**: 사장(L7)이 지시하면 비서(L6)가 외국어로 번역·요약하고, 부서장(L5)이 회의 일정을 잡고, 등기 담당(L4)이 번호를 매겨 누락 없이 보장하고, 배송기획(L3)이 최적 경로를 정하고, 집배원(L2)이 옆 우체국까지 나르고, 트럭·도로(L1)가 실제로 실어 나른다.
- **구체 예시**: 브라우저가 `https://` 요청(L7 HTTP)을 만들고, TLS로 암호화(L6)한 뒤, TCP 443 포트로 세그먼트화(L4)하고, 목적지 IP를 붙여 패킷화(L3)하고, 다음 홉의 MAC을 붙여 이더넷 프레임(L2)으로 만든 다음, 전기 신호(L1)로 랜선에 내보낸다.
- **흔한 오해·주의점**: 실제 인터넷은 OSI 7계층 스택으로 구현되지 않는다. 현실 구현은 TCP/IP 4계층(002 참조)이며, OSI는 교육·트러블슈팅·설계 논의를 위한 참조 모델로 쓰인다. "L4 스위치가 세션까지 본다"처럼 계층 경계를 뭉뚱그리면 감점이다.

## 연결 개념
- TCP/IP 4계층 모델(002) — 실제 인터넷의 사실상(De facto) 표준 구현
- 캡슐화·PDU — 계층을 지날 때마다 헤더가 붙고 단위 이름이 바뀌는 메커니즘
- 프로토콜 3요소(003) — 각 계층의 "약속" 자체를 구성하는 구문·의미·타이밍

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OSI 7계층은 이기종 통신 기능을 독립 계층 7개로 분해한 ISO 국제표준 참조 모델임.
> 2. **가치**: 계층 독립성으로 벤더 종속을 끊고, 장애 발생 시 계층 단위로 원인을 격리(Troubleshooting)할 수 있게 함.
> 3. **판단 포인트**: 실제 구현은 TCP/IP이므로, OSI는 계층별 PDU·장비·프로토콜을 매핑하는 분석 도구로 활용해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|

| 계층 기반 장애 격리 역량 | Ping(L3)·ARP(L2)·Port(L4) 기반 구간 특정 | "호환성이 좋다" 식 빈 추상 표현 |

> 요약: 단순 암기가 아니라 계층별 PDU·장비 매핑과 캡슐화 흐름으로 장애를 격리하는 분석 도구로 서술함.

## Ⅰ. 개요 및 필요성

- 개요: 이기종 통신 기능을 7개 독립 계층으로 나눈 ISO 국제표준(De jure) 참조 모델임
- 배경: SNA·DECnet 등 벤더 종속 규격으로 이기종 장비 간 상호 연동이 불가능하던 한계
- 필요성: 계층 독립성으로 벤더 종속을 끊고, 장애 원인을 계층 단위로 신속히 격리·식별하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
[송신 측: 캡슐화, L7 -> L1로 헤더 부착하며 내려감]
L7 응용 (Data) -> L6 표현 (Data) -> L5 세션 (Data) -> L4 전송 (Segment)
  -> L3 네트워크 (Packet) -> L2 데이터링크 (Frame) -> L1 물리 (Bit)

[매체 전송] L1 비트를 전기/광 신호로 매체에 실어 보냄

[수신 측: 역캡슐화, L1 -> L7로 헤더 제거하며 올라감]
L1 물리 (Bit) -> L2 데이터링크 (Frame) -> L3 네트워크 (Packet)
  -> L4 전송 (Segment) -> L5 세션 (Data) -> L6 표현 (Data) -> L7 응용 (Data)
```

| 계층 | PDU | 주요 역할·프로토콜 | 대표 장비 |
|:---|:---|:---|:---|
| L7 응용 | Data | 사용자 통신 서비스 (HTTP, FTP, SMTP) | L7 스위치, WAF |
| L6 표현 | Data | 인코딩·압축·암호화 (JPEG, TLS) | - |
| L5 세션 | Data | 세션 성립·유지·동기화 (RPC, NetBIOS) | - |
| L4 전송 | Segment | 종단 간 신뢰성·흐름·오류 제어 (TCP, UDP) | L4 스위치 |
| L3 네트워크 | Packet | 최적 경로 라우팅·논리주소 (IP, ICMP) | 라우터, L3 스위치 |
| L2 데이터링크 | Frame | 인접 노드 오류 제어·MAC 주소 (Ethernet) | L2 스위치, 브리지 |
| L1 물리 | Bit | 비트↔신호 변환·매체 전송 (RS-232C, 케이블) | 허브, 리피터 |

> 요약: L1~L3은 네트워크 지원 하위 계층, L5~L7은 사용자 지원 상위 계층, 그 경계를 L4가 종단 신뢰성으로 연결함.

## Ⅲ. 동작원리 및 흐름도

```text
사용자 데이터 → L4 포트 부착(Segment) → L3 IP 부착(Packet) → L2 MAC 부착(Frame) → L1 비트 신호 전송
```

1. **데이터 생성 (L7~L5)**: 응용 데이터를 프로토콜 형식으로 포맷팅하고 표현 계층에서 암호화·압축함
2. **세그먼트화 (L4)**: 송수신 포트 번호와 순서번호를 부착해 종단 간 신뢰성·흐름 제어 체계를 마련함
3. **패킷화·라우팅 (L3)**: 목적지 IP를 부착하고 라우팅 테이블로 다음 홉 경로를 결정함
4. **프레이밍·전송 (L2~L1)**: 다음 홉 MAC과 FCS를 부착해 프레임을 만들고, 비트 스트림으로 매체에 실어보냄

> 요약: 송신은 계층별 헤더를 덧붙이는 캡슐화, 수신은 역순으로 벗기는 역캡슐화로 대칭 동작함.

---

## Ⅳ. 특징

- 계층 독립성: 한 계층 내부 구현을 바꿔도 인접 계층 인터페이스만 지키면 다른 계층은 무영향임
- 표준 참조성: 실제 구현체가 아니라 통신 구조 설계·분석의 기준을 제공함 (실 구현은 TCP/IP)
- 계층별 장애 격리: 장애를 L1~L7 단위로 좁혀 원인 구간을 특정하기 쉬움
- 헤더 오버헤드: 계층마다 헤더가 붙어 페이로드 대비 제어정보 비율이 증가함 (MTU 1500B 기준)
- 상하 계층 대화 제약: 각 계층은 바로 위·아래하고만 통신해 결합도를 낮추나 처리 단계가 늘어남

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | OSI 7계층 | TCP/IP 4계층 |
|:---|:---|:---|
| 성격 | 국제 공식표준(De jure), 참조 모델 | 사실상 표준(De facto), 실제 구현 |
| 계층 수 | 7계층 (응용/표현/세션 분리) | 4계층 (상위 3계층을 응용으로 통합) |
| 제정 주체 | ISO | IETF / 미 국방부(DoD) |
| 신뢰성 주체 | 연결형·비연결형 모두 정의 | 신뢰성은 L4(TCP), 라우팅은 L3(IP)로 분리 |

> 요약: OSI는 구조를 이해·설계하는 개념 뼈대, TCP/IP는 실제 서비스를 구동하는 구현체로 상호보완적임.

- 장애 격리는 하위→상위(Bottom-Up) 순차 점검이 원칙 — L1/L2부터 확인해 상위로 좁힘
- L1/L2 리스크: 케이블 단선·MAC 플래핑 → Link LED·포트 Error 카운트 확인, 포트/케이블 교체
- L3 리스크: 라우팅 루프·서브넷 오설정 → Ping·Traceroute로 단절 구간 식별, TTL 로그 점검
- L4/L7 리스크: 포트 차단·프로세스 다운 → Telnet 포트·HTTP 50x 확인, 방화벽/WAF 정책 검토

## Ⅵ. 실무 적용 및 결론

- 장애 트러블슈팅 자동화: NMS로 L1(링크)~L4(포트) 상태 지표를 수집해 장애 계층을 자동 격리함
- 심층 방어 설계: L3/L4 방화벽(IP·Port)과 L7 WAF(페이로드 검사)를 분리 배치해 Defense in Depth 구성함
- SDN 계층 분리: L2/L3 제어 평면을 중앙 컨트롤러로 분리하고 데이터 평면을 통합 프로비저닝함
- 결론(조건부 판단): OSI는 구현 프로토콜은 아니나, 클라우드·SDN에서 모듈 간 결합도를 낮추는 불변의 설계 기준임
- 결론(향후 방향): 서비스 메시 확산으로 L4/L7 경계가 모호해져, 응용 계층 중심의 가시성 확보 중요성이 커짐

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "OSI 7계층을 설명하시오" | 계층별 역할·PDU·캡슐화 흐름 균등 배분 | TCP/IP 대비 구조 차이, 참조 모델의 가치 |
| 요구사항 명시형 | "계층 기반 장애 조치 방안을 제시하시오" | 역캡슐화 역순(Bottom-Up) 탐색 흐름도 | 계층별 장애 원인·점검 도구(Ping/Telnet), 장비 배치 |

> 요약: 포괄형은 7계층 역할을 고르게, 요구사항 명시형은 장애 격리와 L4/L7 장비 배치로 논점을 좁힘.
