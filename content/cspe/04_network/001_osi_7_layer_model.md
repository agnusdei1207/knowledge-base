# 📖 【암기용】 개념 완전 이해

> 목적: OSI 7계층 모델을 처음 보는 사람도 계층 분리의 이유와 각 계층의 역할을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 네트워크 통신 기능을 7개 책임으로 나눈 참조 모델
- **왜 필요한가**: 장애가 케이블, IP, TCP, 세션, 표현, 애플리케이션 중 어디에서 생겼는지 분리해 진단하기 위함이다.
- **핵심 직관**: 편지를 쓸 때 내용, 봉투, 주소, 우체국 운송을 나누듯 통신도 역할별 층으로 나눈다.

## 깊이 이해
- **배경·문제의식**: 벤더별 폐쇄 프로토콜은 장비 상호 운용을 어렵게 만들었다. ISO OSI 모델은 통신 기능을 물리 전송부터 응용 처리까지 계층화하여 표준 용어와 진단 기준을 제공했다.
- **작동 원리**: 송신 측은 응용 데이터에 계층별 제어정보를 붙여 하위 계층으로 내리고, 수신 측은 하위 계층부터 제어정보를 해석해 상위 계층으로 올린다. 이를 캡슐화와 역캡슐화라 한다.
- **비유**: 회사 문서를 보낼 때 작성자, 번역자, 봉투 담당, 배송 담당이 각자 맡은 일을 수행하는 구조와 같다.
- **구체 예시**: 웹 접속은 L7 HTTP, L4 TCP 443, L3 IP, L2 Ethernet, L1 광/전기 신호가 순서대로 관여한다.
- **흔한 오해·주의점**: 실제 인터넷은 TCP/IP 모델이 구현 기준이지만, OSI 7계층은 장애 위치와 보안 통제 지점을 설명하는 공통 언어로 쓰인다.

## 연결 개념
- TCP/IP 4계층 모델: 실제 인터넷 프로토콜 스택
- 캡슐화(송신 헤더 추가)와 역캡슐화(수신 헤더 제거) 과정
- L2/L3/L4/L7 장비: 계층별 처리 기준이 다른 네트워크 장비

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 준수한다.
> 핵심: OSI 7계층은 암기 문제가 아니라 계층별 책임, PDU, 장비, 장애 진단 포인트를 연결하는 문제이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OSI 7계층 모델은 네트워크 통신 기능을 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 계층으로 분리한 ISO 참조 모델이다.
> 2. **가치**: 계층별 책임 분리로 장애 분석, 보안 통제, 장비 역할, 프로토콜 매핑을 표준 용어로 설명한다.
> 3. **판단 포인트**: 실제 구현은 TCP/IP 중심이나 시험 답안은 OSI 계층, PDU, 장비, 프로토콜 예시를 함께 써야 감점을 피한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층형 네트워크 구조 이해 확인 | 7계층 명칭, 책임, PDU, 대표 프로토콜 | 계층 이름만 나열하고 역할·장비 매핑 누락 |
| 장애 진단 관점 확인 | L1 물리 링크, L2 MAC, L3 IP, L4 포트, L7 HTTP 분리 | TCP/IP 4계층과 OSI 7계층 혼용 |
| 보안·운영 적용 판단 확인 | 방화벽 L3/L4, WAF L7, TLS L5~L7 연계 | OSI가 실제 프로토콜이라는 단정 |

> 요약: OSI 문제는 7계층 암기보다 계층별 책임과 진단·통제 위치를 연결하는 답안이 필요하다.

---

## Ⅰ. 개요 및 필요성

OSI 7계층 모델은 통신 기능을 7개 계층으로 분리한 참조 모델이다. 네트워크 장애는 물리 신호, MAC, IP, TCP, 응용 프로토콜 등 여러 지점에서 발생한다. 계층 분리는 장애 위치를 좁히고, 장비·프로토콜·보안 통제를 계층별로 배치하기 위해 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
Application Data
-> L7 Application -> L6 Presentation -> L5 Session
-> L4 Transport -> L3 Network -> L2 Data Link -> L1 Physical
-> Medium
```

| 계층 | 역할 | 대표 예시 |
|:---|:---|:---|
| L7 응용 | 사용자 서비스 인터페이스 | HTTP, DNS, SMTP |
| L6 표현 | 인코딩, 압축, 암호화 표현 | TLS, ASN.1, JPEG |
| L5 세션 | 세션 수립·유지·종료 | RPC, NetBIOS Session |
| L4 전송 | 종단 간 전송, 포트, 신뢰성 | TCP, UDP, QUIC 전송 기능 |
| L3 네트워크 | 논리 주소, 라우팅 | IP, ICMP, OSPF |
| L2 데이터링크 | 프레임, MAC, 오류 검출 | Ethernet, VLAN, PPP |
| L1 물리 | 전기·광 신호, 매체 규격 | UTP, Fiber, 802.3 PHY |

> 요약: OSI는 사용자 서비스부터 물리 신호까지 책임을 7개 계층으로 분리하고 각 계층에 프로토콜·장비·PDU를 배치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
송신 애플리케이션 데이터
-> L7/L6/L5 처리 -> L4 Segment -> L3 Packet -> L2 Frame -> L1 Bit
-> 전송 매체
-> L1 Bit -> L2 Frame -> L3 Packet -> L4 Segment -> L7 데이터
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 송신 측 상위 계층 데이터 생성 | HTTP status, DNS 응답 코드 |
| 2 | L4 포트·순서·오류 제어 정보 부가 | TCP 3-way handshake, port 0~65535 |
| 3 | L3 IP 주소와 라우팅 정보 부가 | IPv4 TTL, IPv6 Hop Limit |
| 4 | L2 MAC 주소와 FCS 부가 | Ethernet MTU 1500, CRC 오류 |
| 5 | 수신 측 역캡슐화 후 응용 전달 | p95 응답시간, packet loss, retransmission |

> 요약: OSI 동작은 송신 캡슐화와 수신 역캡슐화이며, 장애 검증은 계층별 헤더·상태·지표로 수행한다.

## Ⅳ. 특징

| 구분 | 기존/단일 구조 | OSI 7계층 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 구조 | 벤더 종속 통신 절차 | ISO 7498 기반 계층 참조 | 7계층, 계층별 PDU |
| 진단 | 장애 원인 혼재 | L1~L7 단계별 확인 | ping L3, tcpdump L2~L4, HTTP log L7 |
| 장비 | 기능 구분 불명확 | Hub L1, Switch L2, Router L3, WAF L7 | ACL, port, URL 기준 분리 |
| 한계 | 구현과 문서 일치 어려움 | 실제 인터넷은 TCP/IP 중심 | OSI는 참조 모델로 설명 |

> 요약: OSI는 구현 표준보다 계층별 책임·장비·장애 진단 위치를 정리하는 참조 모델로 가치가 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | TCP/IP 모델 | OSI 7계층 | 선택 기준 |
|:---|:---|:---|:---|
| 목적 | 인터넷 구현 중심 | 통신 기능 설명 중심 | 실제 설계는 TCP/IP, 답안·진단은 OSI 병행 |
| 계층 수 | 4계층 | 7계층 | 표현·세션 분리가 필요한 설명에서 OSI 선택 |
| 운영 활용 | 프로토콜 스택 관리 | 장애 위치 분류 | NOC 장애 분석은 L1부터 L7까지 단계 점검 |

> 요약: TCP/IP는 구현 기준, OSI는 설명·진단 기준이므로 문제 요구에 따라 병행 제시한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 계층 혼동 | OSI와 TCP/IP 계층 수 차이 | L5~L7을 Application 계층으로 매핑 | 답안 매핑표 포함 |
| 진단 누락 | L7 오류를 L3 장애로 오판 | L1 link, L3 ping, L4 port, L7 status 순서 점검 | loss, RTT, SYN retransmission |
| 보안 통제 위치 오류 | 방화벽·WAF 역할 혼재 | L3/L4 ACL, L7 HTTP inspection 분리 | 차단 로그, rule hit count |

> 요약: OSI 적용 리스크는 계층 혼동이며, TCP/IP 매핑표와 L1~L7 점검 순서로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 물리·링크 | interface error 0.1% 이하, MTU 1500/9000 일치 | switch port counter, ethtool |
| 네트워크·전송 | packet loss 0.1% 이하, SYN retransmission 1% 이하 | ping, traceroute, tcpdump |
| 응용 | HTTP 5xx 1% 이하, p95 응답 300ms 이하 | access log, APM, DNS log |

> 요약: OSI 기반 점검은 L1/L2 오류, L3/L4 연결성, L7 응답 지표를 순서대로 확인해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 대응: L1 link up, L2 MAC/VLAN, L3 route, L4 port, L7 status 순서의 점검표를 NOC Runbook에 반영
2. 보안 설계: L3/L4 방화벽 ACL, L7 WAF, TLS 인증서 만료 30일 전 알림으로 계층별 통제 배치
3. 관측성: interface error, packet loss, TCP retransmission, HTTP 5xx, p95 latency를 계층별 대시보드로 분리

**결론 (2줄):**
- 기술사 판단: 장애 분석·보안 통제 설명 문제는 OSI 7계층을 기준으로 쓰고, 실제 구현 문제는 TCP/IP 매핑을 함께 제시함
- 향후 방향: QUIC, TLS 1.3, SDN 환경에서도 계층 책임과 관측 지표를 분리해 운영 가시성을 확보해야 함
