## 미리 알고가기

- SPAN: 스위치가 특정 포트 트래픽을 복사해 분석 포트로 보내는 방식임
- TAP: 물리 링크 중간에서 신호를 분기해 원본 트래픽을 수집하는 장치임
- BPF: 필요한 패킷만 골라 캡처하도록 필터를 거는 방식임
- PCAP: 캡처한 패킷을 저장하는 표준 파일 형식임

## Ⅰ. 개요

- **정의/개념**: 패킷 캡처와 프로토콜 분석은 네트워크를 지나는 패킷을 수집한 뒤, 계층별 헤더와 시간 정보를 해석해 통신 상태와 장애 원인을 확인하는 기술임. 단순한 추정이 아니라 실제 트래픽 증거를 바탕으로 분석한다는 점이 핵심임
- **배경/필요성**: 응답 지연, 연결 실패, 재전송 증가 같은 문제는 서버와 네트워크 원인이 섞여 보이기 쉬우므로 패킷 흐름과 시점 정보를 직접 봐야 원인을 분리할 수 있음

## Ⅱ. 특징

- 패킷 원본을 보기 때문에 애플리케이션 로그보다 더 아래 계층의 문제를 직접 확인할 수 있음
- 어디서 수집하느냐에 따라 보이는 정보와 신뢰도가 달라져 SPAN과 TAP 선택이 중요함
- 필터 없이 전부 저장하면 저장 공간과 분석 시간이 급격히 커지므로 목적에 맞는 수집 범위를 먼저 정해야 함
- TLS 1.3 같은 암호화 환경에서는 페이로드보다 메타데이터와 지연 패턴 분석이 더 중요해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | SPAN | TAP |
|:---|:---|:---|
| 수집 방식 | 스위치가 트래픽을 소프트웨어적으로 복사해 분석 포트로 보냄 | 물리 링크 중간에서 신호를 분기해 분석 장비로 보냄 |
| 장점 | 스위치 설정으로 트래픽 복사 범위를 변경할 수 있음 | 물리 링크에서 신호를 분기하여 스위치 혼잡의 영향을 받지 않음 |
| 한계 | 혼잡 시 미러링 누락이 생길 수 있고 스위치 설정 영향도 받음 | 장비 비용과 배선 작업이 필요하며 물리 삽입 계획이 필요함 |
| 적합한 상황 | 일시적 장애 분석과 현장 점검에 적합함 | 상시 관제, 포렌식, 고속 링크 분석에 적합함 |

> 요약: SPAN은 스위치 기반 임시 수집에, TAP은 상시 관제와 원본 보존이 필요한 구간에 적용함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 수집 지점 | 어느 스위치와 어느 링크에서 패킷을 볼지 정하며, 위치가 잘못되면 원인 구간을 놓침 |
| 필터 | IP, 포트, 프로토콜 조건으로 필요한 패킷만 남겨 분석 범위를 줄임 |
| 저장소 | 타임스탬프와 함께 패킷을 PCAP 형태로 저장해 재분석과 증적 활용을 가능하게 함 |
| 분석기 | 프로토콜을 해석하고 세션 단위로 재구성해 재전송, 지연, 오류 패턴을 읽어 냄 |

```text
+--------+     +--------+     +--------+     +--------+
| Traffic | --> | Capture | --> | Storage | --> | Analyze |
+--------+     +--------+     +--------+     +--------+
```

> 요약: 수집 지점, 필터, 저장, 해석 순서가 맞아야 패킷 분석이 실제 장애 원인까지 이어짐

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 지점선정 | --> | 패킷수집  | --> | 세션재구성 | --> | 원인분석  |
+----------+     +----------+     +----------+     +----------+
```

1. **지점선정**: 장애가 의심되는 구간의 앞뒤 가운데 어디를 볼지 정함
2. **패킷수집**: SPAN이나 TAP로 트래픽을 모으고 필요한 필터를 적용함
3. **세션재구성**: 캡처 데이터를 시간 순서와 흐름 단위로 다시 묶음
4. **원인분석**: 재전송, 지연, 에러, 핸드셰이크 실패 같은 징후를 보고 병목 지점을 찾음

## Ⅵ. 실무 적용 및 유의점

1. 일시적 장애 분석에서는 SPAN으로 의심 구간을 캡처하되 미러링 누락이 생길 수 있으므로 BPF로 범위를 줄이고 캡처 드롭 수와 재전송 비율을 함께 확인함
2. 상시 관제나 포렌식에서는 TAP으로 원본 링크 트래픽을 수집하되 암호화 트래픽은 내용이 보이지 않을 수 있으므로 복호화 지점이나 메타데이터 분석 체계를 같이 두고 패킷 누락률과 분석 성공률로 확인함

## Ⅶ. 결론

패킷 분석은 수집 지점·복사 방식·필터·드롭 수를 확인해야 관측된 패킷과 실제 장애 구간을 연결할 수 있음.
