# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 패킷 캡처·프로토콜 분석은 네트워크 인터페이스를 통과하는 **패킷을 복사·수집(Capture)**하고, OSI 7계층 구조에 맞춰 **역어셈블·해석(Analysis)**하는 기술임.
- **왜 필요한가**: "서버가 느리다"는 현상만으로는 원인(네트워크 지연·서버 처리 지연·재전송)을 특정할 수 없으며, 양단 간 패킷의 타임스탬프·TCP 상태를 직접 확인해야 물증 기반 장애 원인 분리가 가능함.
- **핵심 직관**: 도로에 지나가는 차량을 블랙박스로 녹화(캡처)하고, 녹화 영상을 돌려보며 "이 차는 속도위반(지연)이고 저 차는 불법물품(공격)이네"라고 해석하는 것.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 프로토콜 분석 (상위 키워드) | 수집된 패킷을 계층별 헤더·Payload 구조로 파싱하여 통신 상태를 가시화하는 기술 | 녹화 영상 분석 |
| SPAN (Port Mirroring) | 스위치가 특정 포트의 트래픽을 복사하여 분석 포트로 전달하는 기능 | 통화 녹음 자동 전달 |
| TAP (Test Access Point) | 케이블 중간에 삽입하는 하드웨어 분배기로 트래픽 100% 무결 수집 | 수도관 중간에 설치하는 유량계 |
| Promiscuous Mode | NIC이 자신의 MAC이 아닌 프레임도 모두 수신하는 모드 | 옆 사람 편지도 다 열어보기 |
| BPF (Berkeley Packet Filter) | 커널 레벨에서 조건(IP·Port)에 맞는 패킷만 선별하는 고속 필터 | 우체국 자동 분류기 |
| PCAP | 캡처된 패킷의 타임스탬프·바이너리를 저장하는 표준 파일 포맷 | 블랙박스 녹화 파일 |
| Dissector | PCAP의 바이트 배열을 OSI 계층별 헤더로 파싱하는 분석 엔진 | 영상 프레임 분석기 |
| DPDK (Data Plane Development Kit) | 커널을 우회(Zero-copy)하여 고속 패킷 처리를 구현하는 프레임워크 | 직통 고속도로 |

## 깊이 이해
- **배경·문제의식**: 분산 시스템(MSA·Cloud) 환경에서 애플리케이션 로그만으로는 네트워크 구간의 지연·단절·재전송 원인을 식별하기 어려움. 패킷 캡처는 "가장 확실한 물증"으로, 법적 포렌식 증거로도 인정됨.
- **수집 단계 — SPAN vs TAP**: SPAN은 스위치 SW 설정으로 간편하나 스위치 CPU를 소모하고 대용량 트래픽 시 Drop이 발생함. TAP은 케이블에 HW 분배기를 삽입하여 트래픽 100%를 무결하게 수집하므로, 10Gbps 이상 환경·법적 증거 능력이 필요한 포렌식에서는 TAP이 필수임.
- **필터링 단계 — BPF**: 초당 수백만 패킷 중 분석 대상(특정 IP·Port)만 커널 레벨에서 선별하여 CPU 부하·저장 공간을 절감함. `tcpdump -i eth0 host 10.0.0.1 and port 443` 같은 BPF 문법으로 조건을 지정함.
- **분석 단계 — Dissector**: Wireshark·tshark 등의 Dissector가 PCAP 파일의 바이트열을 Ethernet→IP→TCP→HTTP 순으로 파싱하여 각 헤더 필드를 사람이 읽을 수 있는 형태로 가시화함. TCP Sequence·ACK 번호, 타임스탬프 Delta를 분석하여 RTT·재전송·윈도우 크기 변화를 추적함.
- **비유**: SPAN은 도로에 감시 카메라를 설치하는 것(카메라 성능에 따라 촬영 누락 가능), TAP은 도로에 타이어 홈 센서를 매설하는 것(지나가는 모든 차량을 100% 기록).
- **구체 예시**: 서버 응답이 3초 걸릴 때, 패킷 캡처의 타임스탬프 Delta를 분석하면 "클라이언트 SYN → 서버 SYN-ACK 10ms(네트워크 정상) → 서버 HTTP 200 2990ms 후(DB 쿼리 병목)"으로 지연 원인이 WAS/DB임을 물증으로 증명할 수 있음.
- **흔한 오해·주의점**: "패킷을 캡처하면 모든 해킹을 볼 수 있다"는 오해가 흔하나, 현대 트래픽의 90% 이상이 TLS 1.3으로 암호화되어 Payload를 볼 수 없음. 복호화 키 연동(SSL VA)이나 메타데이터(JA3 핑거프린트·SNI) 분석이 병행되어야 함. 또한 PCAP 파일에 평문 비밀번호·PII가 포함될 수 있으므로, snaplen 제한(헤더만 저장)으로 민감 정보 유출을 방지해야 함.

## 연결 개념
- **IDS/IPS(024)**: IDS의 Out-of-band 수집은 SPAN/TAP을 통한 패킷 캡처와 동일한 메커니즘.
- **네트워크 모니터링(092)**: SNMP·NetFlow는 메타데이터 기반 모니터링, 패킷 캡처는 원본 데이터 기반 정밀 분석.
- **네트워크 포렌식(122)**: 패킷 캡처(PCAP)는 침해사고 조사의 핵심 증거.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 네트워크 트래픽을 TAP/SPAN으로 수집하고 OSI 계층별로 디코딩하여 통신 상태를 가시화하는 물증 기반 분석 기술임.
> 2. **가치**: 장애 원인 분리(Fault Isolation)·지연 분석·침해사고 포렌식에서 "움직일 수 없는 물증"을 제공함.
> 3. **판단 포인트**: 10Gbps 이상 환경에서 Drop 없는 TAP 수집과 커널 우회(DPDK/eBPF) 고속 처리가 분석 신뢰도를 좌우함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 수집 방식 구조적 차이 | SPAN(SW 복사, Drop 위험) vs TAP(HW 분배, 100% 무결) | 분석 툴(Wireshark) 사용법만 나열 |
| 고대역폭 성능 보장 | BPF 커널 필터, DPDK Zero-copy | 패킷 유실(Drop) 시 분석 왜곡 간과 |
| 암호화 환경 대응 | TLS 1.3 한계, JA3 핑거프린트, SSL VA | "패킷이면 다 본다" 식 만능론 |

> 요약: "어떻게 유실 없이 수집하는가(TAP·DPDK)"와 "암호화 환경에서 어떻게 분석하는가(메타데이터·SSL VA)"의 두 축으로 서술해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 네트워크 인터페이스를 통과하는 패킷을 수집하고 OSI 계층별 프로토콜 구조로 역어셈블·분석하는 기술임.
- 배경: MSA·클라우드 분산 환경에서 애플리케이션 로그만으로는 네트워크 구간 지연·단절 원인 식별이 한계임.
- 필요성: RTT 측정·TCP 재전송 추적·침해사고 포렌식 증거 확보를 위해 원본 패킷 기반 정밀 분석이 필수임.

---

## Ⅱ. 구조 및 구성요소

```text
Target Network -> [수집부: TAP/SPAN] -> [필터부: BPF] -> [저장부: PCAP] -> [분석부: Dissector(Wireshark)]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 수집(TAP/SPAN) | 트래픽 복사본 생성 | TAP: HW 분배, 100% 무결 / SPAN: SW 복사, Drop 위험 |
| 필터(BPF) | 조건(IP·Port)에 맞는 패킷만 커널 레벨 선별 | CPU 부하·저장 공간 절감 |
| 저장(PCAP) | 타임스탬프·바이너리 덤프 표준 포맷 | libpcap(Linux), Npcap(Windows) |
| 분석(Dissector) | 바이트열을 OSI 계층별 헤더로 파싱·가시화 | Wireshark, tshark, tcpdump |

> 요약: TAP/SPAN으로 수집 → BPF로 필터 → PCAP으로 저장 → Dissector로 분석하는 파이프라인 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
NIC Promiscuous Mode -> 커널 버퍼 적재 -> BPF 필터 대조 -> User Space 복사 -> PCAP 저장 -> 계층별 디코딩·가시화
```

1. 패킷 수집: NIC을 Promiscuous 모드로 설정하여 자신의 MAC이 아닌 프레임도 모두 수신하고, TAP/SPAN으로 대상 트래픽 복사본을 전달받음.
2. 커널 필터링(BPF): 커널 레벨에서 BPF 규칙(IP·Port·Protocol)과 대조하여 유효 패킷만 선별하고, 나머지는 폐기하여 CPU·저장 부담을 절감함.
3. PCAP 저장: 마이크로초(μs) 단위 타임스탬프와 패킷 바이너리를 PCAP 포맷으로 저장함. 고대역폭 환경에서는 DPDK Zero-copy로 커널 우회 처리함.
4. 프로토콜 분석: Dissector가 PCAP의 바이트열을 Ethernet→IP→TCP→HTTP 순으로 파싱하여 헤더 필드를 가시화하고, 타임스탬프 Delta로 RTT·지연 구간을 식별함.

> 요약: Promiscuous 수신 → BPF 선별 → PCAP 저장 → Dissector 파싱 순서로 동작하며, 고대역폭에서는 DPDK로 커널 병목을 제거함.

---

## Ⅳ. 특징

- SPAN 한계: 스위치 CPU를 소모하고 백플레인 포화 시 패킷 Drop이 발생하며, CRC 에러 프레임은 스위치가 자체 폐기하여 수집 불가함.
- TAP 강점: 케이블에 HW 분배기를 삽입하여 L1 에러 프레임까지 100% 무결 수집이 가능하고, 스위치 부하 영향이 없음.
- 고대역폭 병목: 10Gbps 이상에서 커널-유저스페이스 컨텍스트 스위칭 오버헤드로 패킷 유실 발생 → DPDK·eBPF로 커널 우회 처리가 필수임.
- TLS 암호화 한계: 현대 트래픽의 90% 이상이 TLS 1.3으로 암호화되어 Payload 분석이 불가하며, SSL VA 복호화 장비 연동이나 JA3 핑거프린트(암호화 메타데이터 패턴) 분석이 필요함.
- 민감 정보 위험: PCAP에 평문 비밀번호·PII가 포함될 수 있으므로, snaplen 제한(헤더만 저장)과 접근 통제가 필수임.

> 요약: 법적 포렌식·고대역폭 환경에서는 TAP+DPDK가 필수이며, TLS 암호화 대응은 메타데이터 분석으로 전환되는 추세임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 헤더 분석(Header) | 심층 Payload 분석(DPI) | 선택 기준 |
|:---|:---|:---|:---|
| 범위 | L3/L4(IP·Port·TCP Flag·Seq) | L7(HTTP URI·SQL Query·파일 추출) | 문제 원인 위치(네트워크 vs 앱) |
| 활용 | RTT 측정·라우팅 오류·포트스캔 탐지 | SQLi 탐지·악성코드 추출·데이터 유출 증명 | 성능 진단 vs 보안 분석 |
| 암호화 | TLS에서도 메타데이터(SNI·JA3) 확보 가능 | TLS 1.3+PFS 환경에서는 복호화 키 없이 무력화 | TLS 적용 범위 |

> 요약: TLS 보편화로 Payload(DPI) 분석보다 헤더 타임스탬프·TCP 시퀀스 기반 메타데이터 분석의 중요성이 증대됨.

**리스크·대응:**
- 대용량 패킷 유실: 커널 컨텍스트 스위칭 오버헤드 → DPDK·eBPF Zero-copy 적용 (지표: 캡처 Drop Rate 0.1% 미만)
- 민감 정보 유출: PCAP에 평문 비밀번호·PII 포함 → snaplen 제한(헤더만 저장), PCAP 접근 통제·암호화 (지표: PCAP 내 민감 정보 평문 노출 여부)
- 암호화 가시성 상실: TLS 1.3+PFS 적용 → SSL VA 연동·세션 키 외부 로깅(Keylog) (지표: 전체 수집 패킷 중 평문 분석 가능 비율)

**점검 지표:**
- 수집 신뢰도: 캡처 Drop Rate — 0.1% 미만 유지
- 분석 정밀도: 타임스탬프 해상도 — μs 단위 이상

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 책임 분리(Fault Isolation): 서버 응답 지연 시 양단 패킷 캡처의 타임스탬프 Delta를 분석하여 네트워크 RTT 지연인지 WAS/DB 처리 지연인지 물증으로 증명함.
2. 무손실 수집 아키텍처: 10G 이상 코어망에 광 TAP을 설치하고, 수집 서버에 DPDK 기반 캡처 엔진을 적용하여 유실률 0%를 달성함.
3. 포렌식 증거 확보: 침해사고 시 PCAP을 재생(Replay)하여 악성코드 유입 경로·데이터 유출량(Exfiltration)을 바이트 단위로 증명함.

**결론:**
- 기술사 판단: SPAN의 Drop 한계를 보완할 TAP과 DPDK 가속 아키텍처 설계가 패킷 분석 신뢰도의 핵심이며, 법적 증거 능력이 필요한 포렌식에서는 TAP이 필수임.
- 향후 방향: TLS 1.3 확산으로 Payload 복호화가 어려워짐에 따라, JA3(TLS 핑거프린트)·메타데이터 패턴을 AI로 분석하는 Encrypted Traffic Analytics(ETA) 방향으로 진화하는 추세임.
