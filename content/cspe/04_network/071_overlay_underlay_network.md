## 미리 알고가기

- 언더레이는 실제 라우터, 스위치, IP 경로로 구성된 물리 기반망임
- 오버레이는 언더레이 위에 터널링으로 만든 논리 가상망임
- 캡슐화는 원래 패킷에 추가 헤더를 붙여 다른 네트워크 위로 운반하는 방식임
- MTU는 한 번에 보낼 수 있는 최대 프레임 크기임

## Ⅰ. 개요

- **정의/개념**: 오버레이와 언더레이는 물리적 전달망과 논리적 서비스망을 분리해 보는 구조로, 언더레이는 안정적인 IP 도달성을 제공하고 오버레이는 그 위에 필요한 보안과 격리, 가상 연결을 구현함
- **배경/필요성**: 클라우드와 분산 서비스 환경에서는 물리 토폴로지를 유지하면서 가상 세그먼트와 서비스 경로를 생성·이동해야 하므로 물리 전달과 논리 연결을 분리할 필요가 있음

## Ⅱ. 특징

- 언더레이는 단순하고 안정적인 경로 제공에 집중하고 오버레이는 서비스 정책과 격리에 집중함
- 물리망 변경 없이 터널과 가상 세그먼트 설정으로 논리 연결을 구성함
- 장애 분석에서는 터널 상태와 언더레이 도달성·MTU를 분리해 확인해야 원인 계층을 구분할 수 있음
- 캡슐화 헤더가 추가되므로 MTU, 경로 가시성, 터널 종단 관리가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 언더레이 | 오버레이 |
|:---|:---|:---|
| 주된 역할 | 실제 패킷이 이동할 IP 도달성과 ECMP 경로를 제공함 | 서비스별 가상 연결, 격리, 암호화 같은 논리 기능을 제공함 |
| 대표 기술 | OSPF, BGP, IP 패브릭, 물리 스위칭이 중심임 | VXLAN, GRE, IPsec, SD-WAN 터널이 중심임 |
| 설계 목표 | 단순성, 안정성, 빠른 수렴이 중요함 | 유연성, 멀티테넌시, 이동성이 중요함 |
| 장애 포인트 | 링크, 라우팅, 물리 대역폭 문제를 주로 봄 | 캡슐화, 터널 종단, MTU, 정책 불일치를 주로 봄 |

> 요약: 언더레이는 길을 깔고 오버레이는 그 길 위에 필요한 서비스 구조를 올리는 계층임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 물리 스위치와 라우터 | 언더레이에서 기본 경로와 도달성을 제공하는 하드웨어 계층임 |
| IP 패브릭 | VTEP, 게이트웨이, 터널 종단이 통신할 기반 IP 망임 |
| 오버레이 터널 종단 | 원본 패킷을 캡슐화하고 해제하는 논리 연결 지점임 |
| 캡슐화 헤더 | 원래 트래픽에 추가되는 VXLAN, GRE, IPsec 같은 오버레이 헤더임 |
| 제어 평면 | 오버레이 종단 위치와 정책 정보를 교환하는 관리 계층임 |

```text
+-------------+     +----------------+     +----------------+     +----------------+
| 오버레이 종단   | --> | 캡슐화 헤더       | --> | 언더레이 IP 패브릭  | --> | 원격 오버레이 종단 |
+-------------+     +----------------+     +----------------+     +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| 원본 패킷 생성  | --> | 캡슐화·터널 진입   | --> | 언더레이 경로 전달   | --> | 역캡슐화·서비스 전달 |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **원본 패킷 생성**: 서비스가 실제 전송할 원래 패킷을 만듦
2. **캡슐화와 터널 진입**: 오버레이 종단이 패킷에 추가 헤더를 붙여 터널로 넣음
3. **언더레이 경로 전달**: 언더레이가 IP 경로 기준으로 패킷을 목적 종단까지 전달함
4. **역캡슐화와 서비스 전달**: 원격 종단이 헤더를 제거하고 원래 서비스를 전달함

## Ⅵ. 실무 적용 및 유의점

1. SD-WAN과 데이터센터 오버레이를 운영하는 환경에서는 오버레이 정책만 보고 장애를 판단하면 원인 분석이 빗나가므로 언더레이 경로와 오버레이 터널 상태를 함께 수집하고 터널 가용성 지표와 언더레이 수렴 시간으로 확인함
2. VXLAN이나 IPsec처럼 캡슐화가 두꺼운 환경에서는 MTU 설계를 놓치면 단편화와 성능 저하가 반복되므로 언더레이 점보 프레임과 PMTUD를 함께 검증하고 단편화 건수와 터널 처리량으로 확인함

## Ⅶ. 결론

오버레이와 언더레이의 핵심은 물리망 안정성과 서비스 유연성을 분리해 다루는 데 있으므로 설계와 장애 분석에서도 두 계층을 함께 봐야 함.
