## Ⅰ. 개요
- **정의**: 동적 라우팅이 최적 경로를 계산하는 양대 논리로, 거리/방향 계산과 전체 위상 지도 계산 방식임.
- **배경 및 필요성**: 라우팅 정보 수집 범위와 메트릭 산정 방식에 따른 통신 오버헤드, 수렴 속도 최적화.
- **출제 의도**: 알고리즘 구조(Bellman-Ford vs Dijkstra) 기반 수렴성, 루프 방지, 네트워크 부하 제어 원리 이해

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **거리 벡터** | 이웃에게 받은 라우팅 테이블 정보와 거리(Hop)를 누적해 경로 갱신 | 이웃 소문 기반 길찾기 |
| **링크 상태** | 네트워크 전체 링크 상태를 직접 수집해 다익스트라(Dijkstra)로 독자 계산 | 전체 지도를 그려 직접 탐색 |
| **수렴(Convergence)** | 토폴로지 변경 사항이 모든 라우터에 전파되어 일치된 상태 | 모든 기기의 데이터 동기화 완료 |

> 요약: 거리 벡터는 설정이 단순하나 수렴이 느리고, 링크 상태는 연산이 복잡하나 빠르고 정확함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **[거리 벡터] 테이블 교환**: 자신의 전체 라우팅 테이블을 인접 라우터와 주기적으로 교환함.
2. **[거리 벡터] 간접 계산**: 이웃 정보에 자신의 홉을 더해 최적 경로를 간접 도출함.
3. **[링크 상태] 플러딩**: 자신의 접속 링크 상태 정보(LSA)만 전체 네트워크에 플러딩함.
4. **[링크 상태] 독자 계산**: 수집된 상태 DB를 기반으로 각 라우터가 최단 경로 트리를 직접 생성함.

> 요약: 거리 벡터는 이웃의 지식을 더해 판단하고, 링크 상태는 직접 전체 지도를 구성해 판단함.

## Ⅳ. 문제점
- 거리 벡터의 라우팅 루프 (원인: 장애 소식이 느리게 전파되어 잘못된 무한 순환 경로를 참조함)
- 링크 상태의 초기 플러딩 부하 (원인: 장애 발생 시 LSA 폭주 및 다익스트라 연산 급증으로 장비 부하 유발)
- 메트릭 산정 한계 (원인: 거리 벡터는 홉 수만, 기본 링크 상태는 대역폭만 고려하여 복합적 통신 품질(지연 등) 반영 불가)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 루프 방지 기법 적용 (스플릿 호라이즌, 포이즌 리버스 등을 통해 거리 벡터의 루프 차단)
- **중기 방안**: [중기] 링크 상태 Area 계층화 (OSPF 영역 분할로 LSA 플러딩 및 라우팅 계산 범위를 국소화)
- **장기 방안**: [장기] 하이브리드 라우팅 고도화 (거리 벡터와 링크 상태의 장점을 결합한 EIGRP 등의 유연한 구조 활용)

## Ⅵ. 전망
- 알고리즘의 경계를 넘어 실시간 지연, 패킷 로스 등의 텔레메트리를 반영하는 지능형 경로 계산으로 발전함.
