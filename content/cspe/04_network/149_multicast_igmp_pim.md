# 📖 【암기용】 개념 완전 이해

> 목적: 멀티캐스트와 IGMP, PIM을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 하나의 데이터를 여러 명의 특정 수신자에게 동시에 효율적으로 보내는 통신 방식
- **왜 필요한가**: 1,000명에게 방송을 할 때 유니캐스트(1:1)로 1,000번 보내면 망이 터지고, 브로드캐스트(1:전체)로 보내면 상관없는 사람까지 방해받는다. 멀티캐스트는 "보고 싶은 사람만 봐"라고 한 번만 쏘는 방식이다.
- **핵심 직관**: 아파트 단지에서 방송을 할 때, 집집마다 찾아가서 말하는 게 아니라(유니캐스트), 단지 내 스피커로 방송하되 듣고 싶은 사람만 스피커를 켜는(멀티캐스트) 것과 같다.

## 깊이 이해
- **배경·문제의식**: IPTV, 화상회의, 증권 데이터 전송 등 동일한 실시간 데이터를 대규모 인원에게 보낼 때 대역폭 낭비를 최소화해야 한다.
- **작동 원리**: 두 가지 주요 프로토콜이 협력한다.
  - **IGMP (호스트-라우터)**: "저 이 방송 보고 싶어요"라고 동네 라우터에게 신청하는 프로토콜.
  - **PIM (라우터-라우터)**: "우리 동네에 시청자가 있으니 방송 데이터를 이쪽으로 보내줘"라고 라우터끼리 길을 뚫는 프로토콜.
- **비유**: 구독자(호스트)가 잡지사 대리점(라우터)에 구독 신청을 하는 것이 IGMP고, 대리점들이 본사로부터 잡지를 배달받기 위해 물류 경로를 짜는 것이 PIM이다.
- **구체 예시**: IPTV 채널을 돌릴 때, 셋톱박스가 IGMP Join 메시지를 보내면 네트워크 망에서 해당 채널의 데이터 흐름이 내 쪽으로 연결된다.
- **흔한 오해·주의점**: "멀티캐스트는 무조건 대역폭을 아끼나?" 그렇다. 하지만 네트워크 장비가 멀티캐스트 경로(Tree)를 계산하고 관리해야 하므로 라우터의 부하(CPU/Memory)는 늘어날 수 있다.

## 연결 개념
- **Multicast Group (Class D)**: 224.0.0.0 ~ 239.255.255.255 사이의 전용 주소
- **RP (Rendezvous Point)**: PIM-SM 방식에서 송신자와 수신자가 만나는 '만남의 광장' 라우터
- **IGMP Snooping**: 스위치가 IGMP 메시지를 엿듣고, 방송을 신청한 포트로만 데이터를 전달하는 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 멀티캐스트의 효율성(대역폭 절감)과 이를 구현하기 위한 계층별 프로토콜(IGMP, PIM)의 상호작용 및 트리 구성 방식(SPT, RPT)을 기술적으로 명확히 서술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 멀티캐스트는 특정 그룹에 속한 다수의 수신자에게 단일 데이터 스트림을 전송하여 네트워크 자원 효율성을 극대화하는 1:N 통신 기술이다.
> 2. **가치**: 중복 트래픽 제거를 통한 대역폭 절감 및 송신 서버의 부하 경감을 제공하여, IPTV 및 실시간 금융 데이터 전송의 핵심 인프라로 작용한다.
> 3. **판단 포인트**: 네트워크 규모와 밀도에 따라 Dense Mode(플러딩 방식)와 Sparse Mode(랑데뷰 포인트 방식) 중 적절한 라우팅 프로토콜을 선정해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 멀티캐스트 통신 메커니즘 이해 확인 | IGMP(가입/탈퇴), PIM(경로 생성), Class D 주소 | IGMP와 PIM의 역할(L2/L3 구분) 혼동 |
| 멀티캐스트 라우팅 프로토콜 특성 비교 | PIM-SM(Sparse) vs PIM-DM(Dense) | RP(Rendezvous Point)의 개념 및 필요성 누락 |
| L2 스위치에서의 효율적 처리 방안 파악 | IGMP Snooping, CGMP | 스위치가 전체 포트로 뿌리는(Flooding) 문제점 간과 |

> 요약: 호스트의 그룹 가입(IGMP)과 라우터 간 최적 트리 구성(PIM)의 유기적 흐름을 부각함.

## Ⅰ. 개요 및 필요성

- 정의: 송신자가 보낸 단일 패킷을 네트워크 장비가 복제하여 특정 그룹 주소(Class D)를 가진 다수의 수신자에게 전달하는 방식
- 배경: 유니캐스트의 중복 전송 비효율과 브로드캐스트의 전체 부하 문제를 동시에 해결해야 하는 대규모 방송 서비스 등장
- 필요성: 네트워크 백본 대역폭 90% 이상 절감 가능, 송신 서버 CPU/NIC 부하 최소화, 실시간 서비스의 동시성 보장

## Ⅱ. 구조 및 구성요소

```text
[멀티캐스트 통신 체계]
Source -> [PIM: 라우터 간 트리 구성] -> Last Hop Router -> [IGMP: 호스트 가입 관리] -> Receiver
            |                               |
      (Multicast Tree)               (Group Membership)
```

| 구성요소 | 역할 및 특징 | 핵심 기술 |
|:---|:---|:---|
| IGMP | 호스트와 로컬 라우터 간 그룹 가입/유지/탈퇴 관리 | v1/v2/v3, Query/Report |
| PIM | 라우터 간 멀티캐스트 전달 경로(Tree) 형성 | PIM-SM, PIM-DM, SSM |
| Class D IP | 멀티캐스트 수신 그룹 식별 번호 (224.0.0.0/4) | Well-known / Local Scope |
| Multicast Tree | 데이터 전송을 위해 형성된 루프 없는 경로 | SPT (Source), RPT (Shared) |

> 요약: IGMP는 '누가 듣는가'를 관리하고, PIM은 '어디로 보낼 것인가'를 결정하는 이원화된 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
[멀티캐스트 가입 및 전송 흐름]
Receiver -> [IGMP Report: 그룹 가입] -> Designated Router
                                          |
Source -> [PIM Register] -> Rendezvous Point (RP) <- [PIM Join] <- Designated Router
                               |
Source -> (Data Stream) -> [Shared Tree] -> Designated Router -> Receiver
```

| 단계 | 처리 내용 | 주요 프로토콜 |
|:---:|:---|:---|
| 1 | 수신자가 특정 그룹(예: 239.1.1.1) 가입 의사를 라우터에 알림 | IGMP v2 Join/Report |
| 2 | 수신자 측 라우터가 상위 또는 RP를 향해 경로 생성 요청 | PIM Join 메시지 |
| 3 | 송신자 측 라우터가 데이터를 RP 또는 트리로 송출 | PIM Register / Encapsulation |
| 4 | 형성된 멀티캐스트 트리를 타고 데이터가 수신자들에게 복제 전송 | Multicast Forwarding |

> 요약: 수신자의 요청이 상향으로 전달되어 트리를 만들고, 데이터는 그 트리를 타고 하향으로 복제되어 내려옴.

## Ⅳ. 특징

### 1. PIM 동작 모드 비교
| 구분 | PIM-DM (Dense Mode) | PIM-SM (Sparse Mode) | 판단 포인트 |
|:---|:---|:---|:---|
| 동작 방식 | Flood & Prune (전체 살포 후 차단) | Explicit Join (명시적 요청 시만 전송) | 네트워크 밀도 |
| 트리 구조 | SPT (Source Specific Tree) | RPT (Shared Tree) -> SPT 전환 | 효율성 및 확장성 |
| 핵심 요소 | Neighbor Discovery | **RP (Rendezvous Point)** | 관리 복잡도 |
| 적용 환경 | 수신자가 밀집된 소규모 망 | 수신자가 산재된 대규모 망/인터넷 | 확장성 (Scalability) |

### 2. IGMP 버전별 차이
- **v1**: Query/Report 기반 기본 가입 (탈퇴 메시지 없음)
- **v2**: **Leave Group(탈퇴)** 메시지 추가로 불필요 트래픽 즉시 차단
- **v3**: **Source Specific Multicast (SSM)** 지원 (특정 송신자 선택 가능)

> 요약: 현대 네트워크는 자원 효율이 높은 **PIM-SM**과 탈퇴가 빠른 **IGMP v2/v3**를 주로 조합함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 유니캐스트 (Unicast) | 브로드캐스트 (Broadcast) | 멀티캐스트 (Multicast) |
|:---|:---|:---|:---|
| 전송 부하 | 수신자 수에 비례 (1:N) | 수신자 수와 무관 (1:All) | 수신자 수와 무관 (1:Group) |
| 네트워크 부하 | 매우 높음 | 전체 세그먼트에 영향 | 가입된 경로만 영향 |
| 주소 체계 | Class A, B, C | 255.255.255.255 | Class D (224.x.x.x) |

> 요약: 대규모 실시간 서비스에서는 멀티캐스트가 유일한 대안이며, 망 효율을 80% 이상 개선할 수 있음.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| L2 플러딩 | 스위치가 멀티캐스트를 브로드캐스트로 처리 | **IGMP Snooping** 활성화 | 포트별 트래픽 분석 |
| RP 장애 (SPOF) | PIM-SM의 중심점인 RP 장비 장애 | **Anycast RP**, MSDP 적용 | RP 가용성 (Uptime) |
| 보안 위협 | 비인가 사용자의 그룹 가입 및 스니핑 | IGMP 필터링, 정적 그룹 설정 | 비인가 가입 시도 로그 |

> 요약: L2 구간의 효율을 위해 IGMP Snooping을, L3 구간의 가용성을 위해 Anycast RP를 필히 적용해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 그룹 가입 지연 | 100ms 이내 (채널 전환 속도) | STB 로그 분석 및 실측 |
| 트리 구성 유효성 | 루프 없는 최단 경로 형성 확인 | mtrace, show ip mroute 명령 |
| 대역폭 절감률 | 이론적 절감치 대비 90% 이상 | 백본 링크 점유율 비교 |

> 요약: 가입 속도(사용자 경험)와 트리 구성의 정확도(망 안정성)를 통해 운영 품질을 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **기업용 IPTV/방송 서비스**: 전 사원 대상 실시간 중계 시 PIM-SM과 IGMP v2를 적용하여 사내 망 마비 방지 및 고화질 송출
2. **증권 시세 데이터 전송**: 1ms가 중요한 금융 데이터 전송 시 멀티캐스트를 활용하여 모든 지점에 동일 시점 데이터 도달 보장
3. **Ghost/이미지 백업 시스템**: 수백 대의 PC에 동시에 OS 이미지를 설치할 때 멀티캐스트 전송으로 작업 시간 90% 단축

**결론 (2줄):**
- 기술사 판단: 멀티캐스트는 '성능'이 아닌 '생존'의 문제이며, 대규모 트래픽이 집중되는 메트로 이더넷과 데이터센터의 필수 기술임
- 향후 방향: SDN/NFV와 결합하여 트래픽 상황에 따라 실시간으로 멀티캐스트 트리를 재구성하는 소프트웨어 정의 멀티캐스트로 진화할 것임
