## Ⅰ. 개요
- **정의**: 라우터 간 최적 경로를 결정·교환하는 규약
- **배경/필요성**: 대규모 네트워크에서 수동 경로 설정은 변경 대응이 불가하므로 자동 경로 학습 메커니즘이 필요함
- **비유**: 내비게이션이 실시간 교통정보를 공유해 최단 경로를 안내하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IGP/EGP 분류와 알고리즘 차이 이해 | Distance Vector vs Link State 동작 원리 | 메트릭 기준과 수렴 속도 차이를 혼동하지 않을 것 |

> 요약: 라우터가 네트워크 토폴로지 변화에 자동 적응하여 패킷 전달 경로를 결정하는 프로토콜임

## Ⅱ. 구성요소
```text
Routing Protocol
  +-- IGP (내부)
  |     +-- Distance Vector (RIP)
  |     +-- Link State (OSPF, IS-IS)
  +-- EGP (외부)
        +-- Path Vector (BGP)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 라우팅 테이블 | 목적지별 최적 경로와 메트릭을 저장하는 데이터 구조 | 목적지별 최단 경로 지도 |
| 메트릭 | 경로 선택 기준값(홉 수, 대역폭, 지연 등) | 거리·시간·통행료 등 경로 비용 |
| 수렴(Convergence) | 모든 라우터가 동일한 네트워크 상태를 인지하는 과정 | 모든 내비게이션이 같은 교통정보를 반영하는 상태 |

> 요약: 라우팅 테이블·메트릭·수렴 과정이 프로토콜의 핵심 구성임

## Ⅲ. 절차
```text
토폴로지 변경 --> 변경 감지 --> 경로 정보 교환 --> 최적 경로 계산 --> 테이블 갱신
```
- 1단계: 링크 상태 변경(장애·추가)을 인접 라우터가 감지함
- 2단계: 변경 정보를 인접 또는 전체 라우터에 전파함
- 3단계: 수신 정보를 기반으로 알고리즘(Bellman-Ford, Dijkstra)으로 최적 경로를 계산함
- 4단계: 라우팅 테이블을 갱신하고 패킷 포워딩 경로를 적용함

> 요약: 변경 감지 후 정보 전파·계산·갱신의 4단계로 수렴함

## Ⅳ. 문제점
- 수렴 지연: 대규모 망에서 전파 시간이 길어 일시적 라우팅 루프가 발생함
- 확장성 한계: 라우터 수 증가 시 경로 정보량이 기하급수적으로 증가하여 CPU·메모리 부하가 커짐
- 단일 메트릭 편향: 홉 수만 고려 시 대역폭이 큰 경로를 무시하는 비효율이 발생함

> 요약: 수렴 지연·확장성·메트릭 편향이 주요 한계임

## Ⅴ. 개선방안
1. 단기: Incremental Update 적용으로 변경분만 전파하여 수렴 시간을 단축함
2. 중기: 계층적 라우팅(Area 분할)으로 경로 정보량을 축소하여 확장성을 확보함
3. 장기: 복합 메트릭(대역폭·지연·신뢰도 조합) 기반 경로 선택으로 효율성을 높임

> 요약: 증분 갱신·계층화·복합 메트릭으로 단계적 개선이 가능함

## Ⅵ. 전망
- 발전 방향: SDN 기반 중앙 집중형 라우팅과 분산 프로토콜의 하이브리드 구조로 진화함
- 기술사적 판단: 전통 라우팅은 SDN/SD-WAN과 공존하며, 프로토콜 이해는 네트워크 설계의 기본 소양임
- 기술사 제언: IGP/EGP 분류와 알고리즘 특성을 정확히 구분하고, SDN 연계 시나리오를 함께 학습할 필요
