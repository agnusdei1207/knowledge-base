## 미리 알고가기

- 지연 시간은 패킷이 목적지까지 가거나 응답이 돌아오는 데 걸리는 시간임
- 지터는 패킷마다 지연 시간이 들쭉날쭉한 정도임
- 처리량은 실제로 전달된 데이터 양이고 굿풋은 재전송과 제어 오버헤드를 뺀 유효 데이터 양임
- 분위수는 평균 대신 상위 지연 구간을 보기 위한 값으로 보통 $p95$, $p99$를 많이 씀

## Ⅰ. 개요

- **정의/개념**: 네트워크 KPI는 지연 시간, 지터, 처리량, 손실률 같은 값을 수치로 관리해 서비스 품질과 장애 상태를 판단하는 운영 기준임
- **배경/필요성**: 사용자가 느리다고 말해도 실제 원인은 지연 증가일 수도 있고 손실이나 재전송일 수도 있으므로 원인을 나눠 볼 수 있는 공통 지표가 필요함

## Ⅱ. 특징

- 서비스 종류에 따라 더 민감한 지표가 다르므로 한 가지 수치만으로 품질을 판단할 수 없음
- 평균값은 짧은 지연 급증을 희석할 수 있어 p95·p99와 관측 구간 최대값을 함께 확인함
- 처리량과 손실과 지연은 서로 영향을 주므로 지표를 따로 보되 함께 해석해야 함
- 능동 측정, 장비 카운터, 흐름 데이터를 시간축으로 연결하여 사용자 경로와 원인 구간을 구분함

## Ⅲ. 종류 및 비교

| 판단 기준 | 지연 시간 | 지터 | 처리량·굿풋 | 손실률 |
|:---|:---|:---|:---|:---|
| 의미 | 패킷 전달에 걸린 시간임 | 지연의 흔들림 정도임 | 실제 전송 성과를 보여줌 | 전송 중 사라진 패킷 비율임 |
| 민감한 서비스 | 웹 요청, 거래 처리, 원격 제어 | 음성, 영상, 실시간 제어 | 백업, 대용량 전송, 스트리밍 | 음성, 영상, TCP 성능 전반 |
| 함께 볼 값 | $p95$, $p99$, 왕복 시간 | 버퍼 길이, 큐 상태 | 링크 사용률, 재전송률 | CRC 오류, 드롭 카운터 |
| 해석 주의점 | 평균만 보면 튀는 구간을 놓침 | 낮은 평균 지연에서도 악화될 수 있음 | 링크 속도와 같지 않을 수 있음 | 무선 오류와 혼잡을 구분해야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 능동 측정 도구 | 탐침 패킷을 보내 지연 시간과 손실을 직접 측정함 |
| 장비 인터페이스 카운터 | 사용률과 오류와 드롭을 수집해 회선 상태를 보여줌 |
| 흐름 정보 | 어떤 사용자와 응용이 대역폭을 쓰는지 파악하게 해 줌 |
| 대시보드와 임계치 | 서비스별 목표값과 경보 기준을 한곳에서 관리함 |
| 원인 분석 절차 | 지표 이상이 생겼을 때 혼잡, 장애, 정책 문제를 구분함 |

```text
+-----------+    +-----------+    +-----------+    +-----------+
| 측정 수집    | -> | 지표 계산    | -> | 임계치 비교   | -> | 원인 분석    |
+-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 측정 대상 정의 | -> | 데이터 수집    | -> | KPI 계산      | -> | 기준값 비교    | -> | 조치 후 재확인 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **측정 대상 정의**: 서비스별로 무엇을 볼지와 허용 범위를 정함
2. **데이터 수집**: 탐침, 장비 카운터, 흐름 로그를 모음
3. **KPI 계산**: 지연 시간과 지터와 처리량과 손실률을 산출함
4. **기준값 비교**: 임계치를 넘는 구간과 장비를 찾음
5. **조치 후 재확인**: 정책 변경이나 증설 뒤에 같은 지표로 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 웹 서비스는 평균 응답보다 긴 꼬리 지연이 더 문제가 되므로 $p95$와 $p99$를 함께 보고 라우팅 변경이나 큐 조정 뒤에 응답 지연이 실제로 줄었는지 확인해야 함
2. 음성과 영상은 처리량보다 지터와 손실에 더 민감하므로 우선순위 정책을 적용한 뒤 지터와 패킷 손실과 재전송률이 안정적으로 유지되는지 확인해야 함

## Ⅶ. 결론

네트워크 KPI의 핵심은 숫자를 많이 모으는 데 있지 않고 서비스 품질을 실제로 좌우하는 지표를 골라 같은 기준으로 계속 비교하는 데 있음
