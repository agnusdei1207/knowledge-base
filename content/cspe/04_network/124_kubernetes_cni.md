## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 컨테이너 간 네트워크 연결 및 해제를 표준화된 인터페이스로 제공하는 플러그인임 |
| 배경 | 다양한 네트워크 벤더의 솔루션을 일관된 방식으로 쿠버네티스에 연동 필요 |
| 출제 | 컨테이너 네트워킹 구조, 오버레이 네트워크, NetworkPolicy 적용 |

## Ⅱ. 구성요소
```text
+-----------+        +--------------+        +--------------+
|  Kubelet  | -----> |  CNI Plugin  | -----> |  Pod Network |
| (Manager) | Calls  | (Executable) | Config | (veth, IP)   |
+-----------+        +--------------+        +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Kubelet | 파드 생성을 감지하고 컨테이너 네트워크 구성 요청함 | 작업 반장 |
| CNI 플러그인 | Calico, Cilium 등 실제 네트워크 프로비저닝 실행 파일임 | 배관공 |
| Pod 네트워크 | 파드에 할당된 가상 이더넷 인터페이스와 IP 주소 대역임 | 수도 파이프 |

> 요약: Kubelet의 호출을 받아 CNI가 개별 파드의 네트워크 환경을 구성함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Create | -> | 2. Call   | -> | 3. IPAM   | -> | 4. Return |
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 파드 생성 (Create): Kubelet이 새로운 컨테이너(Pod) 생성을 시작함.
2. CNI 호출 (Call): 네트워크 설정을 위해 구성된 CNI 바이너리를 호출함.
3. IP 할당 (IPAM): CNI가 IPAM을 통해 IP를 부여하고 veth 쌍 구성함.
4. 결과 반환 (Return): 네트워크 구성 완료 상태를 Kubelet에 회신함.

> 요약: 파드 생성 시 네트워크 플러그인을 호출하여 IP 할당 및 라우팅 구성함.

## Ⅳ. 문제점
- 파편화: Calico, Flannel 등 다양한 플러그인별 고유 설정 방식 상이함.
- 성능 저하: iptables 기반 플러그인의 경우 룰 증가 시 트래픽 지연 발생함.
- 보안 복잡성: 파드 간 세밀한 접근 제어(NetworkPolicy) 정책 작성 어려움.

## Ⅴ. 개선방안
- 표준 템플릿 (단기): 운영 환경에 최적화된 CNI 배포 템플릿을 표준화함.
- eBPF 전환 (중기): Cilium 등 eBPF 기반 차세대 CNI로 교체하여 성능 개선함.
- 자동화 보안 (장기): 서비스 메시와 결합하여 선언적 보안 정책 적용 자동화함.

## Ⅵ. 전망
- K8s CNI는 eBPF 기술을 기본 내장하여 커널 오버헤드 없는 초저지연 네트워킹을 제공할 것임.
