## Ⅰ. 개요
- **정의**: 모든 리프 스위치가 모든 스파인 스위치에 풀메시로 연결되는 2-티어 데이터센터 네트워크 토폴로지임
- **배경/필요성**: 전통 3-티어 구조에서 동-서 트래픽 증가 시 STP 병목과 비대칭 경로 문제가 발생하여 균일 지연 구조가 필요함
- **비유**: 모든 교실(리프)이 모든 복도(스파인)와 연결되어 어디서든 동일한 거리로 이동 가능한 학교 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3-티어 대비 장점과 ECMP 원리 | 동-서 트래픽 최적화, 홉 수 균일(최대 2홉), ECMP | 스파인은 L3 포워딩만 수행하고 서버 직접 연결 안 됨 |

> 요약: 풀메시 연결과 ECMP로 동-서 트래픽의 균일 지연을 보장하는 2-티어 토폴로지임

## Ⅱ. 구성요소
```text
        [Spine-1]   [Spine-2]   [Spine-3]
          / | \       / | \       / | \
         /  |  \     /  |  \     /  |  \
   [Leaf-1] [Leaf-2] [Leaf-3] [Leaf-4]
     |  |     |  |     |  |     |  |
   Server   Server   Server   Server
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 스파인 스위치 | 리프 간 L3 포워딩만 수행하는 백본 계층 | 고속도로 교차로 |
| 리프 스위치 | 서버·스토리지가 연결되는 접속 계층(ToR) | 건물 로비 |
| ECMP | 다중 등비용 경로로 트래픽을 분산하는 라우팅 기법 | 다차선 병렬 도로 |

> 요약: 스파인(백본)과 리프(접속)의 풀메시 연결에 ECMP를 적용하는 구조임

## Ⅲ. 절차
```text
용량설계 --> 물리배선 --> 언더레이L3구성 --> 오버레이연동
```
- 1단계: 동-서 트래픽량 기반 스파인/리프 수량 및 업링크 대역폭 설계
- 2단계: 모든 리프-스파인 간 풀메시 물리 배선(광케이블)
- 3단계: BGP/OSPF 기반 언더레이 L3 라우팅 및 ECMP 구성
- 4단계: VXLAN/EVPN 오버레이를 스파인-리프 위에 배포하여 가상 네트워크 연동

> 요약: 용량 설계 후 풀메시 배선, L3 라우팅, 오버레이 순으로 구축함

## Ⅳ. 문제점
- 배선 복잡도 증가: 리프 N × 스파인 M 포트 수만큼 물리 케이블이 필요하여 관리 부담 증가
- 스파인 확장 한계: 스파인 추가 시 모든 리프에 업링크를 추가해야 하므로 포트 고갈 발생 가능
- 남-북 트래픽 비효율: 외부 게이트웨이 연결 설계가 별도로 필요함

> 요약: 배선 복잡도, 스파인 확장 시 포트 한계, 남-북 트래픽 처리가 과제임

## Ⅴ. 개선방안
1. 단기: 구조화 배선 및 자동화된 케이블 관리 시스템 도입으로 운영 부담 경감
2. 중기: 슈퍼스파인 계층 추가(5-Stage Clos)로 스파인 확장성 확보
3. 장기: 보더 리프 전용 설계 및 DCI 연동으로 남-북 트래픽 경로 최적화

> 요약: 배선 자동화, 슈퍼스파인 확장, 보더 리프 설계로 단계적 개선 필요

## Ⅵ. 전망
- 발전 방향: 400G/800G 인터페이스 도입으로 스파인-리프 대역폭이 지속 확대됨
- 기술사적 판단: AI/ML 워크로드의 GPU 클러스터 간 통신에서 균일 지연 보장이 핵심 요구임
- 기술사 제언: 초기 설계 시 오버서브스크립션 비율과 향후 확장 여유를 함께 산정해야 함
