## 미리 알고가기

- 비트 지향 프로토콜은 문자 코드가 아니라 비트 패턴으로 프레임 경계를 구분하는 링크 제어 방식임
- FCS는 프레임 끝에 붙는 오류 검사용 값으로 보통 CRC 계산 결과를 담음
- 비트 스터핑은 데이터 구간에 `01111110`과 같은 플래그 패턴이 나타나지 않게 중간에 0을 끼워 넣는 방식임
- NRM, ARM, ABM은 누가 전송을 주도하는지에 따라 나뉘는 HDLC 동작 모드임

## Ⅰ. 개요

- **정의/개념**: HDLC는 플래그, 제어 필드, FCS를 이용해 프레임 경계와 오류 검출과 흐름 제어를 처리하는 비트 지향 데이터링크 프로토콜임
- **배경/필요성**: 전용 회선이나 점대점 링크에서는 연속된 비트열을 어디서 끊어 읽을지와 오류가 났을 때 어떻게 재전송할지를 정해야 하므로 일관된 프레임 규칙이 필요함

## Ⅱ. 특징

- 시작과 끝을 같은 플래그 패턴으로 표시해 프레임 경계를 분명히 잡음
- I, S, U 프레임으로 데이터 전송과 확인 응답과 링크 제어 역할을 나눔
- 비트 스터핑을 써서 데이터 안에 플래그와 같은 비트열이 나와도 프레임을 잘못 자르지 않음
- 동작 모드에 따라 주국과 종국의 전송 권한 구조를 다르게 가져갈 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | NRM | ARM | ABM |
|:---|:---|:---|:---|
| 전송 주도권 | 주국이 허가할 때만 종국이 전송함 | 종국도 허가 없이 전송할 수 있음 | 양쪽이 대등하게 전송함 |
| 운용 구조 | 중앙 제어형 다중점 회선에 맞음 | 비대칭 운용이 필요한 특수 환경에 맞음 | 점대점 링크에 가장 널리 쓰임 |
| 제어 복잡도 | 구조는 단순하지만 응답 지연이 생길 수 있음 | 운용 사례가 적고 구현이 까다로움 | 유연하지만 양단 상태를 정확히 맞춰야 함 |
| 대표 활용 | 호스트 중심 제어 회선 | 제한적 특수 링크 | PPP 계열 점대점 링크의 기반 개념 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Flag | 프레임 시작과 끝을 알리는 구간으로 `01111110` 패턴을 사용함 |
| Address | 다중점 환경에서 상대 스테이션을 식별하는 필드임 |
| Control | 프레임 종류와 순서 번호와 응답 상태를 담아 흐름 제어와 오류 제어를 수행함 |
| Information | I 프레임에서 실제 사용자 데이터를 담는 구간임 |
| FCS | 전송 중 비트 오류를 검출하기 위한 검사값임 |

```text
+--------+---------+---------+-------------+------+--------+
| Flag   | Address | Control | Information | FCS  | Flag   |
+--------+---------+---------+-------------+------+--------+
                |            |
                v            v
          프레임 종류 결정     오류 검출
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
| 링크 설정    | -> | 프레임 생성   | -> | 비트 스터핑  | -> | 전송·수신     | -> | FCS 검증     |
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
      |                                                                |
      +---------------------- 재전송·응답 제어 -------------------------+
```

1. **링크 설정**: U 프레임으로 동작 모드와 초기 상태를 맞춤
2. **프레임 생성**: 송신 측이 주소와 제어 정보와 데이터와 FCS를 붙임
3. **비트 스터핑**: 데이터 안의 플래그 유사 패턴을 제거해 경계 혼동을 막음
4. **전송·수신**: 상대 측이 플래그를 기준으로 프레임을 분리해 읽음
5. **FCS 검증과 응답**: 오류가 없으면 확인 응답을 보내고, 오류가 있으면 재전송을 유도함

## Ⅵ. 실무 적용 및 유의점

1. 전용 회선이나 레거시 직렬 링크에서는 HDLC 방식이 여전히 유효하지만 양단의 동작 모드와 제어 프레임 해석이 어긋나면 링크가 자주 끊기므로 설정값을 먼저 맞추고 링크 업률과 재전송 횟수와 FCS 오류 수로 확인함
2. 잡음이 많은 회선에서는 비트 스터핑과 FCS만으로는 품질이 충분하지 않을 수 있으므로 상위 계층 재전송과 회선 품질 점검을 함께 운영하고 프레임 폐기율과 응답 지연으로 확인함

## Ⅶ. 결론

HDLC는 단순한 프레임 형식이 아니라 링크 경계와 오류 제어와 전송 권한 구조를 함께 정하는 규칙이므로 회선 성격에 맞는 동작 모드 선택이 핵심임
