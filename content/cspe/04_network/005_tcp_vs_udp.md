## Ⅰ. 개요
- **정의**: 전송 계층의 두 핵심 프로토콜인 TCP(003 참조)와 UDP(004 참조)의 특성 비교
- **배경/필요성**: 서비스 요구사항(신뢰성 vs 실시간성)에 따라 적합한 프로토콜을 선택할 필요가 있음
- **비유**: 등기우편(TCP)과 일반우편(UDP)의 선택과 동일 — 확인이 필요하면 등기, 속도가 우선이면 일반

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로토콜 선택 기준 판단력 | 비교 축: 연결성, 신뢰성, 순서, 속도, 헤더 크기 | 단순 우열 비교가 아닌 용도별 적합성으로 서술 |

> 요약: 서비스 특성에 따라 신뢰성과 실시간성 간 트레이드오프를 판단하는 비교임

## Ⅱ. 구성요소
```text
         TCP                     UDP
  +---------------+       +---------------+
  | Connection-   |       | Connectionless|
  | oriented      |       |               |
  | Reliable      |       | Best-effort   |
  | Ordered       |       | Unordered     |
  | Flow/Congestion|      | No control    |
  | Header: 20B+  |       | Header: 8B    |
  +---------------+       +---------------+
```

| 구성요소 | TCP | UDP |
|:---|:---|:---|
| 연결 방식 | 3-way 핸드셰이크 연결형 | 비연결형, 즉시 전송 |
| 신뢰성 | ACK·재전송으로 보장 | 미보장, 애플리케이션 위임 |
| 순서 보장 | 시퀀스 번호로 순서 복원 | 미보장 |
| 흐름 제어 | 슬라이딩 윈도우 기반 | 미지원 |
| 헤더 크기 | 20~60바이트(옵션 포함) | 8바이트 고정 |
| 적용 사례 | HTTP, FTP, 이메일 | DNS, VoIP, 스트리밍 |

> 요약: TCP는 신뢰성 중심, UDP는 속도 중심으로 용도에 따라 선택함

## Ⅲ. 절차
```text
[요구사항 분석] --> [신뢰성 필요?] --Yes--> [TCP 선택]
                        |
                       No
                        |
                  [실시간성 필요?] --Yes--> [UDP 선택]
                        |
                       No
                        |
                  [혼합 방식 검토] --> [QUIC 등 대안 선택]
```
- 1단계: 서비스의 데이터 특성(용량, 빈도, 손실 허용도) 분석
- 2단계: 신뢰성 요구 시 TCP 선택 — 파일 전송, 웹, 이메일 등
- 3단계: 실시간성 요구 시 UDP 선택 — 음성, 영상, 게임 등
- 4단계: 양쪽 요구가 동시에 있을 경우 QUIC 등 하이브리드 방식 검토

> 요약: 서비스 요구사항 기반으로 신뢰성→TCP, 실시간성→UDP, 혼합→QUIC 순으로 판단함

## Ⅳ. 문제점
- 이분법적 선택 한계: TCP/UDP만으로 다양한 서비스 요구를 충족하기 어려움 — 신뢰성+저지연 동시 요구 증가
- TCP Head-of-Line Blocking: 하나의 패킷 손실이 후속 전체 스트림을 차단 — 멀티플렉싱 환경에서 성능 저하
- UDP 보안 취약: 연결 상태 미관리로 스푸핑·증폭 공격에 취약 — DDoS 반사 공격의 주요 수단

> 요약: 이분법적 선택, HoL 블로킹, 보안 취약이 기존 체계의 한계임

## Ⅴ. 개선방안
1. 단기: 서비스별 프로토콜 선택 가이드라인 수립으로 이분법적 판단 체계화
2. 중기: QUIC 도입으로 UDP 위에 스트림별 독립 전송을 구현하여 HoL 블로킹 해소
3. 장기: DTLS·UDP 인증 헤더 표준화로 비연결형 프로토콜 보안성 강화

> 요약: 가이드라인, QUIC, UDP 보안 강화로 단계적으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: QUIC이 TCP+TLS+HTTP/2 기능을 UDP 위에 통합하며 경계가 변화 중
- 기술사적 판단: TCP/UDP 이분법에서 용도 최적화 프로토콜 선택 체계로 전환 중
- 기술사 제언: 프로토콜 선택 시 지연·손실·보안 3축 기반 정량적 분석 역량이 필요함
