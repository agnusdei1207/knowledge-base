# 📖 【암기용】 개념 완전 이해

> 목적: IIoT를 처음 보는 사람도 제조·설비·네트워크 관점에서 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 산업 설비 데이터를 네트워크로 수집·분석·제어하는 산업용 IoT 구조
- **왜 필요한가**: 공장·발전소·물류 설비는 PLC, 센서, 모터, SCADA가 분산되어 있어 고장 전조와 에너지 낭비를 사람이 즉시 파악하기 어렵다.
- **핵심 직관**: IIoT는 설비의 온도·진동·전류 값을 계속 듣고, MES·ERP·클라우드가 생산 의사결정에 쓰도록 번역하는 계층이다.

## 깊이 이해
- **배경·문제의식**: 기존 OT망은 폐쇄망과 수동 점검 중심이어서 설비 이상을 정비 시점에 발견한다. IIoT는 OPC UA, MQTT, TSN, Edge Gateway를 결합해 현장 데이터를 초 단위로 수집한다.
- **작동 원리**: 센서·PLC가 데이터를 만들고, 게이트웨이가 Modbus·PROFINET·OPC UA 등 현장 프로토콜을 MQTT·HTTPS로 변환한다. Edge는 필터링·이상탐지를 수행하고, 상위 시스템은 OEE, MTBF, 에너지 사용량을 계산한다.
- **비유**: 공장 전체에 건강검진 장비를 붙여 맥박·혈압을 계속 측정하고, 의사가 아닌 시스템이 이상 조짐을 먼저 알리는 구조와 같다.
- **구체 예시**: 회전 설비 진동 RMS가 기준선 2.5배를 10분 이상 초과하면 Edge가 알람을 생성하고, CMMS가 베어링 점검 작업지시를 발행한다.
- **흔한 오해·주의점**: IIoT는 센서 설치만 의미하지 않는다. 시간 동기, 프로토콜 변환, OT 보안, 데이터 품질, 제어망 영향 통제를 함께 설계해야 한다.

## 연결 개념
- OPC UA — 산업 데이터 모델·상호운용성 제공
- TSN — 시간 결정형 이더넷 전송 기반
- Edge Computing — 현장 지연·망 단절 대응

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: IIoT는 IoT 일반론이 아니라 OT 설비 데이터의 수집, 시간성, 보안, 운영 지표를 함께 판단하는 산업 네트워크 문제이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IIoT는 센서·PLC·SCADA 데이터를 Edge와 플랫폼으로 연결해 설비 상태를 수치화하는 산업 데이터 네트워크이다.
> 2. **가치**: OEE, MTBF, 에너지 kWh/제품 단위, 불량률을 데이터 기반으로 측정하여 정비·생산 계획을 조정한다.
> 3. **판단 포인트**: OPC UA·MQTT·TSN·Edge Gateway 선택은 지연시간, 주기성, OT망 격리 수준, 설비 제조사 프로토콜에 따라 달라진다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산업 네트워크와 일반 IoT 차이 확인 | PLC, SCADA, OPC UA, Edge, MES 연결 | 센서 수집만 쓰고 제어망 영향 통제 누락 |
| 실시간성과 데이터 활용 판단 확인 | ms 단위 제어, 초 단위 모니터링, 분 단위 분석 분리 | 모든 데이터를 클라우드로 전송한다고 단정 |
| OT 보안·운영 리스크 확인 | IEC 62443, 망분리, 자산 식별, 패치 절차 | IT 보안 대책만 나열 |

> 요약: IIoT 답안은 설비 데이터 흐름과 OT 제약을 분리해 쓰고, 지표 기반 운영 효과를 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 산업 설비 데이터 연결망
- 배경: PLC·SCADA 중심 OT망은 설비 상태를 현장 패널과 수동 점검에 의존함.
- 필요성: 진동·온도·전류 데이터를 1초~1분 주기로 수집해 고장 전조와 생산 손실을 조기 식별함.
- 범위: 제어 루프는 현장에 두고, 분석·예지정비·에너지 최적화는 Edge와 플랫폼에서 수행함.

---

## Ⅱ. 구조 및 구성요소

```text
Sensor/Actuator -> PLC/RTU -> Edge Gateway -> IIoT Platform -> MES/ERP/CMMS
                      / OPC UA, Modbus, PROFINET
                      / MQTT, HTTPS, Time-series DB
                      / IEC 62443 Zone/Conduit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Sensor/Actuator | 온도·진동·전류·압력 측정 및 물리 제어 | ms~초 단위 샘플링 |
| PLC/RTU | 현장 제어 로직 실행 | 제어 루프는 로컬 유지 |
| Edge Gateway | 프로토콜 변환·필터링·버퍼링 | OPC UA, MQTT, store-and-forward |
| IIoT Platform | 수집·저장·분석·알람 | Time-series DB, rule engine |
| MES/ERP/CMMS | 생산·자재·정비 업무 연계 | OEE, 작업지시, 재고 반영 |

> 요약: IIoT 구조는 현장 제어를 PLC에 남기고 Edge가 산업 프로토콜과 IT 플랫폼 사이를 중계하는 계층 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
설비 상태 측정 -> PLC 수집 -> Edge 정규화 -> 플랫폼 저장
-> 이상탐지/알람 -> MES/CMMS 작업 반영 -> 현장 조치 피드백
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 센서가 진동·온도·전류 데이터를 생성 | 샘플링 주기, 결측률 |
| 2 | PLC가 현장 제어와 데이터 태그를 분리 | 제어 주기 영향 0건 |
| 3 | Edge가 OPC UA/MQTT 메시지로 변환 | 태그 매핑 오류율 |
| 4 | 플랫폼이 저장·분석·알람을 수행 | 알람 지연, 오탐률 |
| 5 | 업무 시스템이 정비·생산 계획을 갱신 | MTTR, 계획정비 비율 |

> 요약: IIoT는 측정, 정규화, 분석, 업무 반영 순서로 설비 데이터를 운영 의사결정에 연결한다.

## Ⅳ. 특징

| 구분 | 기존 OT 운영 | IIoT 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 데이터 수집 | 수동 점검·SCADA 화면 확인 | 센서 태그 자동 수집 | 1초~1분 주기, Time-series DB |
| 프로토콜 | 제조사별 폐쇄 프로토콜 | OPC UA, MQTT, REST 변환 | Pub/Sub, 정보 모델 |
| 지연 요구 | 제어망 중심 | 제어·모니터링·분석 계층 분리 | 제어 ms, 분석 초~분 |
| 운영 지표 | 장애 후 정비 | 예지정비·OEE 관리 | MTBF, MTTR, OEE |

> 요약: IIoT는 제조사별 OT 데이터를 표준 인터페이스로 정규화하여 설비 상태를 지표로 관리하게 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | IIoT | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | SCADA 단독 모니터링 | Edge+Platform+MES 연계 | 설비 수 100대 이상 또는 다공장 통합 |
| 통신 | Fieldbus 폐쇄망 | OPC UA/MQTT over IP | 벤더 혼재, 원격 분석 필요 |
| 운영 | 사후정비 | 조건기반 정비 | MTBF, 예비품 리드타임 |

> 요약: IIoT는 단일 설비보다 다수 설비·다공장·벤더 혼재 환경에서 투자 판단 근거가 커진다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 제어망 간섭 | 분석 트래픽이 PLC망에 유입 | VLAN, QoS, SPAN/TAP 수집 | PLC scan time 변동 |
| 데이터 품질 저하 | 태그명 불일치·센서 보정 누락 | 태그 사전, 캘리브레이션 절차 | 결측률, 이상값 비율 |
| OT 침해 확산 | 게이트웨이 계정·패치 미흡 | IEC 62443 Zone/Conduit, allowlist | 미인가 접속, 취약점 조치일 |

> 요약: IIoT 리스크는 제어망 영향, 데이터 품질, OT 침해 확산이며 네트워크 분리와 태그 거버넌스로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 수집 신뢰도 | 태그 결측률 1% 이하 | Edge 로그, Time-series DB |
| 설비 운영 | MTTR 20% 감소, OEE 산출 | CMMS, MES 실적 |
| 보안 운영 | 미인가 세션 0건, 패치 SLA 30일 | NAC, 취약점 스캔 |

> 요약: IIoT 성공 여부는 연결 장치 수보다 데이터 결측률, 설비 지표, 미인가 접속 건수로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 설비 자산·태그 사전을 먼저 작성하고 PLC, 센서, 게이트웨이를 IEC 62443 Zone/Conduit 기준으로 분류함.
2. OPC UA Gateway와 MQTT Broker를 Edge에 배치하고 1초 수집 데이터와 이벤트성 알람 데이터를 별도 토픽으로 분리함.
3. OEE, MTBF, MTTR, 에너지 kWh/제품 단위 지표를 MES·CMMS와 연동해 작업지시와 원인분석에 반영함.

**결론 (2줄):**
- 기술사 판단: 제어 주기 ms 단위 설비는 로컬 제어를 유지하고, 분석·예지정비는 Edge와 플랫폼으로 분리하는 설계를 선택함.
- 향후 방향: IIoT는 OPC UA FX, TSN, Edge AI와 결합해 현장 데이터의 시간성·상호운용성·운영 지표 관리를 확대함.
