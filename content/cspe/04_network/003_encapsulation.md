## Ⅰ. 개요
- **정의**: 송신 시 데이터를 전송 가능한 형태로 포장(캡슐화)하고, 수신 시 이를 풀어(역캡슐화) 원본을 추출하는 과정임.
- **배경 및 필요성**: 계층 간 독립성을 유지하면서 프로토콜 제어 정보를 추가/해석하기 위함.
- **출제 의도**: 계층형 통신 모델에서 데이터 단위(PDU)의 변화와 제어 정보 처리 과정에 대한 이해 파악

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **Payload (페이로드)** | 상위 계층으로부터 전달받은 실제 전송하려는 데이터(사용자 정보) | 택배 상자 안의 실제 물품 |
| **Header (헤더)** | 라우팅, 포트, 제어 정보 등을 담고 있으며 페이로드 앞에 붙는 데이터 | 택배 상자의 송장 |
| **Trailer (트레일러)** | 에러 검출(FCS 등)을 위해 데이터 후미에 추가되는 제어 정보 | 택배 상자의 봉인 씰 |

> 요약: 데이터 전송 시 헤더, 페이로드, 트레일러가 결합되어 프로토콜 데이터 단위(PDU)를 형성함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **데이터 전달**: 응용 계층에서 생성된 메시지가 전송 계층으로 내려옴.
2. **헤더 추가 (캡슐화)**: 각 계층(TCP, IP, MAC 등)에서 목적에 맞는 제어 정보(Header)를 부착함.
3. **물리적 전송**: 완성된 프레임이 물리 매체를 통해 비트 스트림 형태로 수신 측에 도달함.
4. **헤더 제거 (역캡슐화)**: 수신 측 하위 계층부터 차례로 헤더와 트레일러를 분석/제거하며 데이터만 추출함.

> 요약: 송신 시 PDU 단위로 제어 정보가 덧붙여지며, 수신 시 역순으로 검증 및 제거가 수행됨.

## Ⅳ. 문제점
- 과도한 헤더 크기로 인한 대역폭 낭비 (원인: 소형 페이로드 전송 시 헤더가 차지하는 비율이 비정상적으로 높음)
- 캡슐화 과정의 프로세싱 지연 (원인: 여러 계층을 거치며 헤더를 연산하고 부착하는 시간 소요)
- MTU 초과로 인한 단편화 발생 (원인: 캡슐화 후 프레임 크기가 네트워크 최대 전송 단위를 초과함)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 헤더 압축 기법 적용 (RoHC 등 기술을 활용하여 불필요한 제어 정보를 최소화)
- **중기 방안**: [중기] 하드웨어 오프로딩(Offloading) 활용 (NIC가 캡슐화 처리를 전담하여 CPU 부하 경감)
- **장기 방안**: [장기] 계층 융합형(Cross-layer) 프로토콜 도입 (제어 정보를 통합 처리하여 단편화 및 지연 방지)

## Ⅵ. 전망
- IoT 환경에서는 페이로드가 매우 작으므로, 경량화된 캡슐화 프로토콜(CoAP 등)의 활용이 확대될 전망임.
