## 미리 알고가기

- 분산 클라우드는 중앙 리전, 온프레미스, 엣지에 워크로드와 관리 기능을 분산하는 구조임
- 오버레이는 물리망 위에 논리 주소와 터널로 가상 네트워크를 구성함
- 정책 드리프트는 환경별 설정이 달라져 의도한 정책과 실제 상태가 불일치하는 현상임
- Egress 비용은 클라우드 외부나 다른 리전으로 데이터를 전송할 때 발생하는 비용임

## Ⅰ. 개요

- **정의/개념**: 분산 클라우드 네트워킹은 중앙 클라우드, 멀티클라우드, 온프레미스, 엣지의 연결·보안·DNS·관측 정책을 공통 제어 체계로 운영하는 구조임
- **배경/필요성**: 워크로드가 여러 위치에 배치되면 환경별 라우팅과 보안 정책이 달라지므로 지연, 비용, 데이터 주권을 반영한 경로와 정책을 일관되게 관리해야 함

## Ⅱ. 특징

- 중앙 제어 평면이 위치별 게이트웨이와 오버레이 정책을 배포함
- 사용자와 워크로드 위치에 따라 지연과 Egress 비용을 고려해 경로를 선택함
- 공통 신원과 세그먼트 정책으로 환경 간 접근 범위를 통제함
- 제어 평면 장애와 벤더 종속은 여러 클라우드·엣지 구간에 동시에 영향을 줄 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 클라우드 네트워킹 | 분산 클라우드 네트워킹 |
|:---|:---|:---|
| 연결 범위 | 단일 리전·사업자 내부 연결 | 멀티클라우드·온프레미스·엣지 연결 |
| 경로 기준 | 리전 내부 라우팅 정책 | 위치·지연·비용·규제 조건 |
| 정책 운영 | 사업자별 정책과 도구 | 공통 제어 평면과 정책 모델 |
| 운영 위험 | 리전 장애와 설정 오류 | 정책 드리프트, 경로 복잡도, 벤더 종속 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 중앙 제어 평면 | 경로, 세그먼트, 보안 정책을 정의·배포함 |
| 클라우드·엣지 게이트웨이 | 위치별 오버레이 종단과 정책 집행을 담당함 |
| 글로벌 DNS·서비스 발견 | 사용자와 서비스를 가까운 위치로 연결함 |
| 보안 정책 엔진 | 신원과 워크로드 속성으로 접근을 통제함 |
| 통합 관측 계층 | 위치별 지연, 손실, 흐름, 정책 상태를 수집함 |

```text
[중앙 제어 평면]
   | 정책·경로 배포
[클라우드 A] <-> [온프레미스] <-> [엣지] <-> [클라우드 B]
```

## Ⅴ. 원리 및 절차

1. **요구 분석**: 워크로드의 지연, 비용, 데이터 주권 조건을 확인함
2. **연결 구성**: 위치별 게이트웨이와 오버레이 경로를 생성함
3. **정책 배포**: 공통 세그먼트와 보안 정책을 각 위치에 적용함
4. **경로 선택**: DNS와 라우팅이 상태와 정책에 맞는 위치를 선택함
5. **정합성 검증**: 실제 경로와 정책 상태를 의도한 구성과 비교함

## Ⅵ. 실무 적용 및 유의점

1. 엣지 처리로 사용자 지연을 줄이더라도 클라우드 간 데이터 이동이 늘면 Egress 비용이 증가하므로 p95 지연, 위치별 전송량, Egress 비용을 함께 확인해야 함
2. 환경별 정책 드리프트는 비인가 경로와 장애 원인이 되므로 정책을 코드로 관리하고 배포 전 검증과 롤백을 적용하며 드리프트 건수와 정책 적용 실패율을 점검해야 함

## Ⅶ. 결론

분산 클라우드 네트워킹은 여러 실행 위치를 공통 연결·보안·관측 정책으로 운영하며, 지연·비용·규제와 정책 정합성을 기준으로 경로를 선택해야 함.
