# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 네트워크 패킷의 어느 계층(Layer) 정보를 보고 길을 찾아주느냐에 따라 나뉘는 장비 분류입니다.
- **필요성**: 단순히 주소만 보고 전달하는 것을 넘어, 서비스 종류를 구분하고 부하를 분산하며 보안을 강화하기 위해 상위 계층 정보를 읽는 똑똑한 스위치가 필요합니다.
- **핵심 직관**: **"패킷의 겉봉투만 보느냐, 내용물까지 읽느냐"**의 차이입니다.

## 깊이 이해
- **배경 (참조 계층의 진화)**:
  - **L2 (Data Link)**: MAC 주소만 봅니다. 같은 동네(LAN) 안에서 길 찾기.
  - **L3 (Network)**: IP 주소를 봅니다. 다른 동네(Internet)로 길 찾기. (라우터와 비슷)
  - **L4 (Transport)**: 포트 번호(TCP/UDP)를 봅니다. "이건 웹 트래픽(80)이니까 저 서버로 보내!" (로드밸런싱 시작)
  - **L7 (Application)**: 실제 데이터 내용(HTTP URL, 쿠키 등)을 읽습니다. "이건 동영상 요청이니까 미디어 서버로 보내!" (정밀 제어)
- **작동 원리 (분석의 깊이)**:
  - 하위 스위치(L2, L3)는 하드웨어(ASIC) 칩으로 처리해서 **속도가 매우 빠릅니다**.
  - 상위 스위치(L4, L7)는 패킷을 뜯어서 분석해야 하므로 **기능은 강력하지만 속도는 상대적으로 느려질 수 있습니다**.
- **비유 (물류 센터 분류)**:
  - **L2**: 송장의 이름(MAC)만 보고 해당 선반으로 분류.
  - **L3**: 송장의 주소(IP)를 보고 해당 지역 트럭에 싣기.
  - **L4**: 상자 겉면의 '취급주의' 표시(Port)를 보고 전문가에게 배정.
  - **L7**: 상자를 열어서 내용물(Payload)이 '신선식품'인지 확인하고 냉장고로 보냄.

## 연결 개념
- **Load Balancer**: L4, L7 스위치의 핵심 기능으로, 트래픽을 여러 서버에 골고루 나눠주는 역할.
- **WAF (Web Application Firewall)**: L7 스위칭 기술을 응용하여 웹 공격을 막는 보안 장비.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: OSI 7계층 중 장비가 참조하는 데이터 헤더 정보의 범위에 따라 구분되는 네트워크 중계 및 제어 장치임.
> 2. **가치**: 하위 계층(L2/L3)은 와이어스피드 기반의 고속 전송을, 상위 계층(L4/L7)은 세션 제어 및 콘텐츠 기반의 지능형 서비스 최적화를 제공함.
> 3. **판단 포인트**: 상위 계층 분석 시 발생하는 지연(Latency)과 정밀한 트래픽 제어 사이의 트레이드오프를 고려한 계층적 네트워크 설계가 필수적임.

## Ⅰ. 계층별 스위치 정의 및 참조 정보 비교

| 구분 | 주요 참조 정보 | 기능적 핵심 | 관련 프로토콜/단위 |
|:---:|:---|:---|:---|
| **L2 스위치** | **MAC 주소** | 동일 네트워크 내 프레임 전달 | Ethernet, Frame |
| **L3 스위치** | **IP 주소** | 서로 다른 네트워크 간 라우팅 | IP, ICMP, Packet |
| **L4 스위치** | **Port 번호** | 전송 계층 기반 부하 분산 (SLB) | TCP/UDP, Segment |
| **L7 스위치** | **Payload 내용** | 애플리케이션 콘텐츠 기반 제어 | HTTP, Cookie, URL |

## Ⅱ. 스위칭 메커니즘 상세 분석

### 1. L2/L3: 하드웨어 기반 고속 전송
- **L2**: MAC Table(CAM)을 기반으로 목적지 포트 결정. Flooding, Learning, Forwarding 수행.
- **L3**: 라우팅 테이블을 하드웨어 칩인 **FIB(Forwarding Information Base)**에 복사하여 와이어스피드(Wire-speed) 라우팅 수행.

### 2. L4/L7: 세션 및 콘텐츠 기반 지능형 제어
- **L4 (SLB)**: TCP/UDP 세션을 관리하며 Round Robin, Least Connection 등의 알고리즘으로 서버 부하 분산.
- **L7 (Content Switching)**: HTTP 헤더, Cookie, URL 패턴을 분석하여 사용자별/콘텐츠별 최적의 서버로 연결 (Persistence 지원).

## Ⅲ. L4 스위치 vs L7 스위치 심층 비교

| 비교 항목 | L4 스위치 | L7 스위치 |
|:---:|:---|:---|
| **분산 기준** | IP, Port, 프로토콜 | URL, Cookie, Payload, HTTP Header |
| **주요 기능** | 단순 부하 분산, 서비스 포트 체크 | 콘텐츠 기반 스위칭, 보안(WAF), 캐싱 |
| **장점** | 처리 속도가 빠름, 저렴함 | 매우 정교한 제어 가능, 보안성 높음 |
| **단점** | 정교한 제어 불가 (콘텐츠 모름) | 패킷 분석 오버헤드로 지연 발생 가능 |

## Ⅳ. 주요 기술적 특징: 지능형 트래픽 관리

### 1. Health Check
- 서버의 상태를 주기적으로 감지(ICMP, TCP, HTTP)하여 장애 발생 시 서비스 그룹에서 즉시 제외.
### 2. Persistence (Session Sticky)
- L7 스위칭의 핵심으로, 사용자의 세션 정보(Cookie 등)를 기억하여 동일한 사용자를 계속 같은 서버로 연결해 서비스 연속성 보장.
### 3. SSL Termination (Offloading)
- L7 스위치가 암복호화 과정을 대신 처리하여 웹 서버의 CPU 부하를 경감시키고 보안 검사 수행.

## Ⅴ. 네트워크 계층별 배치 전략 (Design)
- **Access 계층**: L2 스위치 배치, VLAN 분할 및 단말 연결.
- **Distribution 계층**: L3 스위치 배치, VLAN 간 라우팅 및 정책 적용.
- **Core 계층 (Data Center)**: L4/L7 스위치 배치, 서버 부하 분산 및 정밀 보안 통제.

## Ⅵ. 기술사적 통찰: '하드웨어'에서 '소프트웨어'로
- **가상화의 파동**: 과거에는 비싼 전용 장비로만 가능했던 L4/L7 스위칭이 이제는 **Nginx, HAProxy, AWS ELB** 같은 소프트웨어 기반(NFV)으로 완전히 대체되는 추세임.
- **Zero Trust와 L7**: IP 기반 보안(L3)은 한계에 도달함. 이제는 사용자의 ID와 앱의 내용을 확인하는 **L7 기반의 제로 트러스트** 접근 제어가 보안 아키텍처의 핵심이 됨.
- **결론**: 스위칭 계층에 대한 이해는 단순한 장비 선택을 넘어, 고가용성 서비스 설계와 심층 방어 체계 구축을 위한 **"네트워크 엔지니어링의 나침반"**임.
