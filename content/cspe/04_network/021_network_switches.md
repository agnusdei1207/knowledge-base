# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 네트워크 스위치는 OSI 참조 모델의 **특정 계층 헤더**를 참조하여 패킷의 포워딩 경로를 결정하는 장비이며, 참조하는 계층에 따라 L2(MAC)·L3(IP)·L4(Port)·L7(Payload) 스위치로 분류됨.
- **왜 필요한가**: 트래픽 폭증과 서비스 다양화로 MAC 주소만으로는 세밀한 라우팅·부하 분산·보안 필터링이 불가하여, 상위 계층 정보를 분석하는 스위칭이 요구됨.
- **핵심 직관**: L2는 우편번호(MAC)만 보고 배달하는 집배원, L3는 상세 주소(IP)로 건물을 찾는 택배 기사, L4는 내선 번호(Port)로 담당자에게 연결하는 교환원, L7은 편지 내용(Payload)을 읽고 부서를 정밀 배분하는 비서.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| OSI 참조 모델 (상위 키워드) | 네트워크 통신을 7계층으로 분리한 표준 모델, 스위칭 계층 분류의 기준 | 건물 층수(1F~7F) |
| MAC 테이블 | L2 스위치가 Source MAC과 포트를 매핑해 저장하는 포워딩 DB | 사무실 좌석 배치도 |
| FIB (Forwarding Information Base) | L3 스위치가 라우팅 테이블을 하드웨어(ASIC)로 복사한 고속 검색 테이블 | 건물 간 배송 경로표의 즉시 조회판 |
| ASIC (Application-Specific IC) | 패킷 포워딩 전용으로 설계된 하드웨어 칩, 와이어스피드 처리 보장 | 우편 분류 자동 기계 |
| SLB (Server Load Balancing) | L4/L7 스위치가 여러 서버로 트래픽을 분산하는 기능 | 상담 전화를 대기 중인 상담원에게 배분 |
| DPI (Deep Packet Inspection) | L7 스위치가 Payload 내용(HTTP 헤더·URI·쿠키)까지 분석하는 기술 | 소포 내용물 X-ray 검사 |
| TCAM (Ternary CAM) | 0/1/X(Don't Care) 3진 매칭으로 ACL·라우팅을 고속 검색하는 하드웨어 메모리 | 와일드카드 검색이 가능한 전화번호부 |
| 와이어스피드 | 포트의 물리 대역폭과 동일한 속도로 패킷을 처리하는 것 | 도로 제한속도 그대로 달리는 것 |

## 깊이 이해
- **배경·문제의식**: 허브(L1)는 수신 프레임을 모든 포트로 복제(플러딩)하여 충돌이 빈번했음. L2 스위치가 MAC 학습으로 충돌을 없앴으나 브로드캐스트 도메인 분리(019 VLAN)·서브넷 간 라우팅(L3)·세션 기반 부하 분산(L4)·콘텐츠 기반 필터링(L7)에는 한계가 있어 상위 계층 스위칭으로 진화함.
- **L2 스위치 작동 원리**: 수신 프레임의 Source MAC을 포트와 매핑하여 MAC 테이블에 학습하고, Destination MAC을 테이블에서 검색해 해당 포트로만 유니캐스트 포워딩함. 테이블에 없으면 플러딩(모든 포트로 전송). VLAN(019)·STP(020) 기능이 결합됨.
- **L3 스위치 작동 원리**: 패킷의 목적지 IP를 FIB에서 검색하여 최적 경로 포트로 하드웨어 라우팅함. 라우터와 기능은 동일하나 ASIC 기반 하드웨어 처리로 와이어스피드를 보장함. Inter-VLAN 라우팅(019)의 핵심 장비임.
- **L4 스위치 작동 원리**: IP + TCP/UDP 포트 번호로 세션을 식별하고, SLB 알고리즘(Round Robin·Least Connection 등)에 따라 여러 서버로 트래픽을 분산함. NAT 또는 DSR 방식으로 동작함(022 로드밸런서에서 심화).
- **L7 스위치 작동 원리**: TCP 세션을 프록시로 종단한 뒤 HTTP 헤더·URI·쿠키·Payload를 DPI로 분석하여 콘텐츠 기반 라우팅(URL별 서버 배분)·보안 필터링(WAF)을 수행함. TLS Termination 기능으로 암호화 해독 후 검사가 가능함.
- **비유**: L2는 사내 메일을 같은 층(VLAN) 내에서 자리 번호로 전달, L3는 다른 건물(서브넷)로 주소를 보고 전달, L4는 대표 전화를 내선 번호로 상담원에게 분배, L7은 민원 내용을 읽고 담당 부서로 정밀 배분.
- **구체 예시**: 웹 서비스 구성 시, L3 스위치가 서브넷 간 라우팅을 처리하고, 앞단의 L4가 TCP 80/443 트래픽을 3대의 WAS로 Round Robin 분산하며, L7(WAF 기능)이 SQL Injection 패턴이 포함된 요청을 차단함.
- **흔한 오해·주의점**: "L7이 L4보다 무조건 좋다"는 오해가 흔하나, 상위 계층을 분석할수록 패킷당 처리 지연(Latency)이 증가함. 모든 트래픽을 L7으로 처리하면 병목이 되므로, Edge는 L2/L3, Core는 L4/L7으로 목적에 맞게 계층별 배치해야 함.

## 연결 개념
- **VLAN(019)**: L2 스위치의 브로드캐스트 도메인 분할, L3 스위치의 Inter-VLAN 라우팅.
- **로드 밸런서(022)**: L4/L7 스위치의 SLB 기능을 별도 장비·소프트웨어로 구현한 심화 주제.
- **SDN(066)**: 제어부(Control Plane)와 전송부(Data Plane)를 분리해 스위칭 유연성을 극대화.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: L2~L7 스위치는 OSI 계층별 헤더(MAC→IP→Port→Payload)를 참조하여 포워딩 경로를 결정하는 장비 분류임.
> 2. **가치**: 상위 계층을 참조할수록 라우팅 세밀도·보안성이 향상되나, 패킷 분석 깊이에 비례하여 처리 지연이 증가하는 트레이드오프가 존재함.
> 3. **판단 포인트**: 트래픽 특성(볼륨 vs 정밀 제어)에 따라 L2/L3(와이어스피드 포워딩)와 L4/L7(세션 분산·콘텐츠 필터링)의 배치 비율이 성능을 결정함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층별 스위칭 동작 원리 구분 | MAC 학습, FIB 하드웨어 라우팅, 세션 기반 SLB, DPI 분석 | L2~L7 기능의 단순 나열에 그침 |
| 트레이드오프·설계 적용 역량 | 상위 계층 분석 시 지연 증가 vs 제어 세밀도 향상 상충 관계 | "L7이 L2보다 성능이 좋다" 식의 단순 서술 |

> 요약: 계층별 참조 정보·테이블·처리 방식의 차이를 구분하고, 성능-세밀도 트레이드오프에 기반한 배치 전략을 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: OSI 특정 계층 헤더(MAC·IP·Port·Payload)를 참조하여 패킷 포워딩 경로를 결정하는 네트워크 장비 분류임.
- 배경: 브로드캐스트 스톰(L2 한계)·트래픽 폭증·보안 위협 대응으로 상위 계층 분석 요구가 증가함.
- 필요성: 10Gbps 이상 환경에서 와이어스피드 포워딩과 세밀한 트래픽 제어를 동시에 달성하기 위해 목적별 계층 스위치 배치가 필수임.

---

## Ⅱ. 구조 및 구성요소

```text
Incoming Packet -> [L2] MAC Table Lookup -> [L3] FIB Lookup
                                             |
                                             +-> [L4] Session Table / SLB -> [L7] DPI / Payload Parsing -> Egress
```

| 구성요소 | 참조 정보 | 주요 기능·테이블 |
|:---|:---|:---|
| L2 스위치 | Src/Dst MAC 주소 | MAC 학습·포워딩, VLAN(019), STP(020) |
| L3 스위치 | Src/Dst IP 주소 | FIB 기반 하드웨어 라우팅, Inter-VLAN, ACL |
| L4 스위치 | IP + TCP/UDP Port | 세션 기반 SLB, NAT/DSR, Sticky Session |
| L7 스위치 | HTTP 헤더·URI·쿠키·Payload | 콘텐츠 기반 라우팅, WAF, TLS Termination |

> 요약: 계층이 올라갈수록 MAC→IP→Port→Payload로 참조 정보가 깊어지며, 테이블·기능의 복잡도가 증가함.

---

## Ⅲ. 동작원리 및 흐름도

```text
프레임 수신 -> 계층별 헤더 디캡슐레이션 -> 식별자 파싱(MAC/IP/Port/URI) -> 포워딩 룰·테이블 대조 -> 목표 포트 전송(또는 Drop)
```

1. 헤더 디캡슐레이션: 수신 프레임에서 해당 계층의 헤더를 추출함. L2/L3는 ASIC이 와이어스피드로 처리하고, L7은 TCP 재조립 후 Payload를 파싱함.
2. 식별자 파싱: L2는 MAC, L3는 IP, L4는 IP+Port, L7은 HTTP URI·쿠키·헤더를 식별자로 추출함.
3. 테이블 대조: MAC 테이블(L2)·FIB(L3)·세션 테이블(L4)·정규표현식 룰셋(L7)과 대조하여 포워딩 대상을 결정함. TCAM(094)이 고속 매칭을 지원함.
4. 포워딩·필터링: 매칭된 포트로 전송하거나, 보안 룰 위반 시 Drop 처리함. L7은 프록시로 동작하여 별도 TCP 세션을 확립함.

> 요약: 모든 스위치는 헤더 파싱 → 테이블 대조 → 포워딩 순서로 동작하며, 상위 계층일수록 파싱 깊이와 오버헤드가 증가함.

---

## Ⅳ. 특징

- 처리 속도 트레이드오프: L2/L3는 ASIC 기반 와이어스피드(수십~수백 Gbps)를 보장하나, L4/L7은 세션 수·룰 복잡도에 비례하여 지연이 증가함.
- 제어 세밀도: L2/L3는 서브넷·호스트 단위 제어이나, L4/L7은 사용자·애플리케이션·URL 단위까지 세밀한 트래픽 제어가 가능함.
- 하드웨어 의존성: L2/L3는 ASIC 중심, L4/L7은 CPU/NPU·소프트웨어 비중이 높아 수평 확장(Scale-out) 필요성이 큼.
- 보안 기능 차이: L3는 ACL로 IP 기반 필터링, L4는 SYN Flood 방어, L7은 SQL Injection·XSS 등 Payload 기반 공격 탐지·차단(WAF)이 가능함.

> 요약: L2/L3는 대용량 단순 포워딩, L4/L7은 세션 분산·보안 필터링에 특화되며 목적에 맞는 계층 배치가 핵심임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | L4 로드밸런싱 | L7 로드밸런싱 | 선택 기준 |
|:---|:---|:---|:---|
| 분산 기준 | IP·TCP/UDP 포트 | URI·HTTP 헤더·쿠키·Payload | 앱 의존적 라우팅 필요 여부 |
| 세션 유지 | Source IP 기반 바인딩 | 쿠키 기반 Sticky Session | 모바일(IP 변동) 환경 여부 |
| 오버헤드 | 낮음(TCP 상태만 유지) | 높음(Payload 파싱·TLS 해독) | TPS 요구량·허용 지연 |

> 요약: 대용량 단순 분산은 L4(NAT/DSR), MSA API 라우팅·모바일 세션 유지는 L7(Reverse Proxy)이 필수임.

**리스크·대응:**
- L7 DPI 병목: Payload 분석 시 CPU 부하 증가 → ASIC/NPU 오프로딩, 룰셋 최적화 (지표: p95 Latency)
- 세션 테이블 고갈: DDoS(SYN Flood) 시 동시 세션 폭증 → SYN Cookie 적용, Connection Rate Limit 설정 (지표: Concurrent Sessions)

**점검 지표:**
- 성능: 패킷 포워딩 Latency — L2/L3 기준 수 μs, L7 기준 p99 1ms 이내
- 가용성: Health Check 기반 서버 장애 감지 시간 — 3초 이내 풀 제외

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 경계망(L2/L3): 10G L3 스위치를 코어에 배치하여 와이어스피드 라우팅 및 ACL 기반 DDoS 1차 방어를 수행함.
2. 서비스망(L4): WAS 앞단에 L4 스위치를 배치하여 Round Robin·Least Connection 기반 SLB로 수평 확장을 구현함.
3. 애플리케이션망(L7): API Gateway(Envoy·NGINX)를 L7 프록시로 배치하여 URL 기반 라우팅·TLS Termination·WAF 기능을 통합 제공함.

**결론:**
- 기술사 판단: Edge는 L2/L3로 와이어스피드 포워딩, Core는 L4/L7로 세밀한 세션 분산·보안 필터링을 구성하여 성능-제어 트레이드오프를 최적화함.
- 향후 방향: 하드웨어 스위치의 한계를 넘어 소프트웨어 정의 네트워킹(SDN, 066)·eBPF 기반 데이터플레인·Service Mesh(Envoy Sidecar)로 스위칭 유연성이 확장되는 추세임.
