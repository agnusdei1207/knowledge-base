## 미리 알고가기

- L2 스위치: MAC 주소를 보고 같은 LAN 안에서 프레임을 전달하는 장비임
- L3 스위치: IP 주소를 보고 VLAN 간 라우팅까지 처리하는 장비임
- L4 스위치: 전송 계층 포트 정보를 보고 세션 단위 분산을 수행하는 장비임
- L7 스위치: URL, 쿠키, HTTP 헤더 같은 응용 계층 정보를 보고 요청을 제어하는 장비임

## Ⅰ. 개요

- **정의/개념**: 스위칭 계층 분류는 장비가 패킷의 어느 계층 정보를 읽고 전달 결정을 내리느냐에 따라 L2, L3, L4, L7로 나누는 방식임. 계층이 올라갈수록 더 많은 문맥을 보고 제어하지만 처리 비용도 함께 커짐
- **배경/필요성**: 단말 연결만 처리하는 망과, VLAN 간 라우팅이 필요한 망, 애플리케이션별 분산과 보안 검사가 필요한 망은 요구가 다르므로 계층별로 다른 판단 기준을 가진 스위치가 필요함

## Ⅱ. 특징

- L2와 L3는 주로 ASIC에서 MAC·IP 기반 전달을 처리하고, L4와 L7은 세션·애플리케이션 정보를 분산 정책에 사용함
- 상위 계층으로 갈수록 부하 분산, 보안 정책, 콘텐츠 분기 같은 정밀 제어가 가능해짐
- 하위 계층 장비로는 서비스별 정책 제어가 어렵고, 상위 계층 장비만으로는 모든 구간을 처리하기 부담됨
- 따라서 실무에서는 계층별 장비를 분리 배치해 속도와 제어 능력을 함께 확보함

## Ⅲ. 종류 및 비교

| 판단 기준 | L2 스위치 | L3 스위치 | L4 스위치 | L7 스위치 |
|:---|:---|:---|:---|:---|
| 참조 정보 | MAC 주소를 기준으로 프레임을 전달함 | IP 주소와 라우팅 정보를 기준으로 패킷을 전달함 | IP와 포트 정보를 기준으로 세션을 분산함 | URL, 쿠키, 헤더 같은 애플리케이션 정보를 기준으로 요청을 분산함 |
| 대표 역할 | 단말 접속과 VLAN 내부 전달에 적합함 | VLAN 간 통신과 정책 기반 라우팅에 적합함 | 서버 풀 간 빠른 세션 분산에 적합함 | 콘텐츠 기반 분기와 웹 보안 정책에 적합함 |
| 적용 기준 | 같은 LAN의 프레임 전달에 사용함 | VLAN 간 IP 라우팅에 사용함 | IP·포트 기반 세션 분산에 사용함 | URL·헤더·사용자 기반 요청 분기에 사용함 |
| 주의할 점 | 브로드캐스트와 루프 통제가 핵심임 | 라우팅 정책과 ACL 충돌을 주의해야 함 | 애플리케이션 상태를 직접 보지 못함 | TLS 복호화와 콘텐츠 해석 비용으로 지연이 커질 수 있음 |

> 요약: 계층이 올라갈수록 더 정교하게 제어할 수 있지만, 처리 비용과 설계 복잡도도 함께 증가함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 헤더 파서 | 장비가 MAC, IP, 포트, HTTP 헤더 가운데 어디까지 읽을지 결정하는 출발점임 |
| 전달 테이블 | MAC 테이블, 라우팅 테이블, 서버 풀 매핑처럼 실제 전달 대상을 찾는 정보가 저장됨 |
| 정책 엔진 | ACL, NAT, 로드 밸런싱 규칙, 콘텐츠 분기 규칙처럼 단순 전달 외의 판단을 수행함 |
| 상태 정보 | 상위 계층 스위치에서는 세션 상태, 쿠키, 헬스 체크 결과 같은 추가 문맥을 유지해야 함 |

```text
+--------+     +-----------+     +-----------+     +---------+
| Ingress| --> | Header     | --> | Lookup /  | --> | Egress  |
| Packet |     | Parsing    |     | Policy     |     | Forward |
+--------+     +-----------+     +-----------+     +---------+
```

> 요약: 스위칭 계층의 차이는 결국 어디까지 해석하고, 어떤 테이블과 정책으로 전달을 결정하느냐의 차이임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 패킷수신 | --> | 계층해석  | --> | 정책판단  | --> | 목적지전달 |
+----------+     +----------+     +----------+     +----------+
```

1. **패킷수신**: 장비가 프레임이나 패킷을 수신함
2. **계층해석**: 장비 종류에 따라 MAC, IP, 포트, 콘텐츠까지 필요한 범위만 해석함
3. **정책판단**: 테이블 조회와 보안, 부하 분산, 세션 정책을 적용함
4. **목적지전달**: 선택한 포트, 다음 홉, 서버로 트래픽을 전달함

## Ⅵ. 실무 적용 및 유의점

1. 사무실과 캠퍼스망에서는 액세스 계층에 L2, 분배 계층에 L3를 두어 브로드캐스트 범위와 VLAN 간 라우팅을 분리하되 루프 방지와 ACL 정책이 충돌하지 않게 설계하고 MAC 학습 수와 라우팅 지연으로 확인함
2. 인터넷 서비스 구간에서는 L4나 L7 스위치로 부하 분산과 보안 제어를 수행하되 L7을 과도하게 앞단에 두면 지연과 복호화 비용이 커지므로 헬스 체크 방식과 TLS 처리 위치를 함께 정하고 응답 시간과 세션 실패율로 확인함

## Ⅶ. 결론

스위칭 계층을 고르는 기준은 장비 이름이 아니라, 어떤 계층 정보까지 읽어야 서비스 요구와 운영 비용을 함께 만족시킬 수 있는지에 있음.
