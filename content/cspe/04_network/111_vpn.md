## 미리 알고가기

- 터널은 공용망 위에 논리적인 전용 통신 경로를 만드는 방식임
- IPsec은 IP 계층에서 터널과 암호화를 제공하는 표준임
- SSL VPN은 웹 브라우저나 전용 클라이언트로 애플리케이션 접속을 보호하는 방식임
- WireGuard는 단순한 구성과 가벼운 처리로 주목받는 현대적 VPN 프로토콜임

## Ⅰ. 개요

- **정의/개념**: VPN은 공용망 위에 암호화된 터널을 만들어 지사와 본사 또는 원격 사용자가 사설망처럼 안전하게 통신하도록 하는 네트워크 보안 기술임
- **배경/필요성**: 전용선을 모든 지점에 깔기에는 비용이 크고 원격 근무도 늘어났으므로, 인터넷을 쓰면서도 기밀성과 무결성을 확보할 연결 방식이 필요함

## Ⅱ. 특징

- 공용망을 활용하므로 전용선보다 구축 범위와 비용 면에서 유연함
- 암호화와 인증으로 전송 구간의 기밀성과 무결성을 지킬 수 있음
- 네트워크 단위로 넓게 연결하면 사용자는 편하지만 내부 노출 범위가 커질 수 있음
- 사용자 수와 지점 수가 늘수록 키 관리와 정책 관리와 성능 튜닝이 중요해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | IPsec VPN | SSL VPN | WireGuard |
|:---|:---|:---|
| 동작 계층 | IP 계층에서 네트워크 간 터널을 만듦 | 전송·응용 계층 중심으로 접속을 보호함 | 경량 터널 프로토콜로 네트워크 연결을 제공함 |
| 주된 환경 | 지사 간 상시 연결에 적합함 | 원격 사용자와 애플리케이션 접속에 적합함 | 간단한 운영과 고성능이 필요한 환경에 적합함 |
| 운용 특성 | 표준화가 잘 돼 장비 호환성이 좋음 | 배포와 사용이 상대적으로 쉬움 | 설정이 단순하고 처리 부담이 작음 |
| 유의점 | 주소 변환 장비와 정책 충돌을 점검해야 함 | 애플리케이션 단위 권한 통제가 중요함 | 생태계와 운영 표준 정착 수준을 함께 봐야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VPN 클라이언트 | 사용자나 지사 장비에서 터널을 시작함 |
| VPN 게이트웨이 | 암호화 터널 종단과 정책 적용을 담당함 |
| 인증 체계 | 사용자나 장비의 신원을 확인함 |
| 키 교환 기능 | 세션 키를 협상하고 주기적으로 갱신함 |
| 내부 자원 | 터널 뒤에서 실제 서비스를 제공함 |

```text
+-------------+    암호화 터널    +--------------+    내부 통신    +-----------+
| 사용자·지사 장비 | <--------------> | VPN 게이트웨이 | -----------> | 내부 자원   |
+-------------+                    +--------------+                +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[접속 요청] -> [인증] -> [키 교환] -> [터널 생성] -> [암호화 통신]
```

1. **접속 요청**: 사용자나 지사 장비가 VPN 게이트웨이에 연결을 요청함
2. **인증**: 계정이나 인증서나 다중 인증으로 신원을 확인함
3. **키 교환**: 세션 키와 암호화 매개변수를 협상함
4. **터널 생성**: 논리 경로를 만들고 라우팅 정책을 적용함
5. **암호화 통신**: 내부 서비스와 데이터를 암호화해 주고받음

## Ⅵ. 실무 적용 및 유의점

1. 지사 간 상시 연결은 VPN이 전용선보다 경제적이지만 경로 품질이 흔들리면 업무가 바로 끊기므로 이중 회선과 자동 재협상과 경로 감시를 함께 두고 터널 가용률과 재연결 시간과 지연 변화를 같이 확인함
2. 원격 사용자 VPN은 내부망 범위를 넓게 노출하기 쉬우므로 다중 인증과 최소 권한과 분할 터널 정책을 함께 적용하고 비인가 접근 시도와 동시 세션 수와 내부 자원 접속 범위를 계속 봐야 함

## Ⅶ. 결론

VPN의 핵심은 인터넷 위에 안전한 터널을 만드는 데 있으나 실제 선택은 연결 범위와 권한 통제 수준과 운영 복잡도를 함께 보고 결정해야 함.
