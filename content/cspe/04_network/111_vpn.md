# 📖 【암기용】 개념 완전 이해

> 목적: VPN을 처음 보는 사람도 터널, 암호화, 인증, 운영 한계를 연결해 이해하게 만든다.

## 한눈에
- **개요**: VPN은 공용망 위에 암호화 터널을 만들어 사설망처럼 통신하게 하는 원격접속 기술이다.
- **왜 필요한가**: 재택·지사·클라우드 접속은 인터넷을 지나므로 패킷 도청, 변조, 출처 위장이 발생할 수 있다.
- **핵심 직관**: 인터넷 도로 위에 전용 차선을 새로 까는 것이 아니라, 차량 안에 잠금 장치와 신분 확인 절차를 넣는 방식이다.

## 깊이 이해
- **배경·문제의식**: 전용회선은 회선비와 개통 시간이 크고, 인터넷 직접 노출은 인증 우회와 패킷 도청 위험이 있다.
- **작동 원리**: 단말과 VPN 게이트웨이는 IKEv2, TLS, WireGuard Handshake로 상호 인증하고 대칭키를 만든 뒤 ESP, TLS Record, UDP 캡슐화로 데이터를 보호한다.
- **비유**: 회사 건물에 들어갈 때 경비실에서 신분증을 확인하고, 이후 봉인된 사내 우편 봉투로 문서를 전달하는 절차와 같다.
- **구체 예시**: IPsec은 사이트 간 터널에 주로 쓰이고, SSL VPN은 브라우저·에이전트 원격접속에 쓰이며, WireGuard는 UDP 51820과 Curve25519 기반 키 교환으로 단순한 구성을 제공한다.
- **흔한 오해·주의점**: VPN은 터널 내부 통신을 보호하지만, 감염 단말이 터널에 접속하면 내부망 스캔과 계정 탈취가 그대로 발생할 수 있다.

## 연결 개념
- IPsec ESP/IKEv2 - 네트워크 계층 사이트 간 터널 구성
- SSL VPN/TLS - 애플리케이션 접근과 원격 사용자 접속
- ZTNA - 네트워크 접속 대신 애플리케이션 단위 인가 수행

# 📝 【답안용】 시험 답안 템플릿

> 목적: VPN 답안은 터널 암호화 나열이 아니라, 접속 범위·인증·키 교환·운영 지표를 분리해 기술한다.
> 핵심: IPsec·SSL·WireGuard의 적용 위치와 제로트러스트 전환 한계를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: VPN은 인터넷 구간에 인증·암호화·캡슐화를 적용해 사설망 접근 경로를 만드는 터널링 기술이다.
> 2. **가치**: IPsec ESP/IKEv2, SSL/TLS, WireGuard를 목적별로 선택해 지사, 재택, 클라우드 관리망 접속을 구성한다.
> 3. **판단 포인트**: 전체 네트워크 접근이 필요한지, 애플리케이션 단위 접근이면 충분한지에 따라 VPN과 ZTNA를 구분한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 원격접속 보안 구조 이해 확인 | 인증, 키 교환, 터널 암호화, 라우팅 정책 | 암호화만 쓰고 인증·인가·로그를 누락 |
| VPN 유형 선택 역량 확인 | IPsec, SSL VPN, WireGuard 적용 구간 비교 | 세 기술을 동일 계층 기술로 취급 |
| 운영 리스크 판단 확인 | Split tunnel, 계정 탈취, 내부망 이동, 접속 로그 | VPN 접속 후 내부망 전면 허용으로 작성 |

> 요약: VPN 문제는 터널 방식보다 접속 범위와 통제 지점을 어떻게 설계하는지 확인하는 문제이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 공용망 기반 암호화 터널
- 배경: 지사·재택·클라우드 운영자가 인터넷을 통해 내부 자원에 접속함.
- 필요성: IKEv2, TLS 1.3, WireGuard로 인증·암호화·무결성 검증을 수행함.
- 판단 기준: 사용자 단위 접속은 SSL VPN·ZTNA, 망 대 망 접속은 IPsec을 우선 검토함.

---

## Ⅱ. 구조 및 구성요소

```text
User/Branch -> VPN Client/Router -> Internet -> VPN Gateway
             -> Auth/Key Exchange -> Encrypted Tunnel -> Private Resource
             +-> Log/SIEM -> Access Review
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| VPN Client | 단말 인증서, 계정, 터널 인터페이스를 관리 | 에이전트 변조와 버전 편차 점검 필요 |
| VPN Gateway | IKEv2, TLS, WireGuard 세션 종료 | HA 구성, 동시 접속 수, 암호 스위트 관리 필요 |
| Auth/Key Exchange | 사용자·장비 인증 후 세션키 산출 | MFA, X.509, EAP, PSK 오남용 통제 |
| Routing Policy | Full tunnel 또는 Split tunnel 경로 결정 | 내부 대역 노출 범위와 지연시간을 함께 판단 |
| Log/SIEM | 접속 성공·실패, 소스 IP, 세션 시간을 기록 | 계정 탈취 탐지와 감사 증적에 사용 |

> 요약: VPN 구조는 클라이언트, 게이트웨이, 키 교환, 라우팅 정책, 로그가 함께 동작해야 접속 범위를 통제한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접속 요청 -> 사용자/장비 인증 -> 키 교환 -> 터널 생성
-> 라우팅 정책 적용 -> 내부 자원 접속 -> 로그 수집 -> 세션 종료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 클라이언트가 게이트웨이 주소와 프로파일을 선택 | 허용 단말, 인증서 유효기간, MFA 성공 |
| 2 | IKEv2/TLS/WireGuard가 세션키를 협상 | PFS 적용, 약한 암호 스위트 차단 |
| 3 | ESP/TLS/UDP 터널이 패킷을 캡슐화 | 패킷 무결성, 재전송, MTU 단편화 확인 |
| 4 | 정책 라우팅이 내부 대역 접근을 결정 | Split tunnel ACL, DNS 누출 여부 |
| 5 | 접속 로그가 SIEM으로 전달 | 실패율, 비정상 위치, 세션 지속시간 분석 |

> 요약: VPN은 인증 후 키를 만들고, 터널을 생성한 뒤, 라우팅 정책과 로그로 내부 접근을 제한한다.

---

## Ⅳ. 특징

| 구분 | 기존 직접 접속 | VPN 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 전송 보호 | 평문 또는 애플리케이션별 보호 | 터널 단위 암호화 | IPsec ESP, TLS 1.3, ChaCha20-Poly1305 |
| 접속 범위 | 방화벽 포트 직접 노출 | 내부 대역을 터널 뒤에 배치 | ACL, RFC1918 대역, per-user route |
| 운영 비용 | 전용회선 개통 필요 | 인터넷 회선 활용 | HA 게이트웨이 2대 이상 구성 |
| 한계 | 외부 노출 포트 증가 | 접속 후 내부망 이동 가능 | NAC, EDR, ZTNA 병행 필요 |

> 요약: VPN은 전송 구간 보호와 접속 편의성을 제공하지만, 터널 내부 인가를 별도 정책으로 제한해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | IPsec VPN | SSL VPN | WireGuard |
|:---|:---|:---|:---|
| 계층 | L3 터널 | L4/L7 원격접속 | L3 UDP 터널 |
| 주요 용도 | 지사 간, 클라우드 VPC 연결 | 사용자 원격접속, 포털 접근 | 경량 사이트 간, 개발자 접속 |
| 핵심 기술 | ESP, AH, IKEv2 | TLS, 웹 포털, 에이전트 | Curve25519, NoiseIK, UDP 51820 |
| 선택 기준 | 라우팅 대역 고정 | 앱별 접속과 브라우저 호환 | 단순 구성과 코드베이스 축소 |

> 요약: 망 대 망은 IPsec, 사용자 앱 접속은 SSL VPN, 경량 L3 터널은 WireGuard를 우선 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 계정 탈취 | 비밀번호 단일 인증 | MFA, 조건부 접근, 인증서 바인딩 | 실패 로그인율, 해외 IP 접속 수 |
| 내부망 이동 | 터널 후 대역 전체 허용 | per-user ACL, microsegmentation | 차단 이벤트, 내부 스캔 탐지 |
| DNS 누출 | Split tunnel 설정 오류 | 사내 DNS 강제, DoH 정책 통제 | 외부 DNS 질의 건수 |
| 게이트웨이 병목 | 모든 트래픽 Full tunnel 집중 | HA, 지역별 PoP, 대역폭 증설 | 동시 세션, p95 지연, CPU 70% 이하 |

> 요약: VPN 리스크는 접속 전 인증, 접속 후 인가, 터널 운영 지표를 분리해 관리해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 암호 설정 | TLS 1.2 이상, IKEv2, PFS 적용 | 설정 감사, 취약 암호 스캔 |
| 접속 품질 | p95 접속 지연 2초 이하, 터널 재연결 10초 이하 | VPN 로그, APM, 사용자 체감 조사 |
| 보안 증적 | 사용자, 단말, 소스 IP, 세션 ID 기록 | SIEM 대시보드, 감사 샘플링 |
| 접근 통제 | 역할별 허용 대역 0.0.0.0/0 금지 | 정책 리뷰, 방화벽 룰 비교 |

> 요약: VPN 도입 효과는 암호 설정, 접속 품질, 보안 증적, 접근 통제의 네 지표로 확인한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 지사 연결은 IPsec ESP/IKEv2와 BGP 라우팅을 사용하고, 터널별 PSK 대신 인증서 기반 인증을 적용함.
2. 재택 사용자는 SSL VPN 또는 WireGuard에 MFA와 단말 보안 상태 점검을 결합하고, Split tunnel ACL을 사용자 그룹별로 분리함.
3. 접속 로그는 SIEM으로 전송하고, 비정상 위치·심야 접속·대량 실패 이벤트를 MTTD 10분 이내 탐지 규칙으로 등록함.

**결론 (2줄):**
- 기술사 판단: 망 단위 연결이면 VPN을 적용하고, SaaS·업무 앱 단위 접근이면 ZTNA 또는 per-app tunnel을 적용함.
- 향후 방향: VPN은 제로트러스트 정책, EDR 상태, CASB 로그와 결합된 하이브리드 원격접속 구조로 전환됨.
