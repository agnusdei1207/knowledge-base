## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 대규모 망에서 라우팅 정보(LSA)를 계층적 Area로 분할하여 최단 경로(SPF)를 계산하는 프로토콜 |
| **배경/필요성** | 단일 영역 설계 시 발생하는 과도한 링크 상태 플러딩 및 라우터 CPU 연산 부하 방지 필요 |
| **출제 의도** | 링크 상태 라우팅의 계층 설계(Area 0), LSA 타입, ABR/ASBR의 트래픽 제어 능력 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Area 1  |       | Area 0   |       |  Area 2  |
|  (Stub)  | <---> | (Backbone| <---> | (NSSA)   |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Area 0 (백본) | 모든 트래픽이 경유해야 하는 핵심 영역이자 토폴로지 중심 | 고속도로 분기점 |
| LSA | 네트워크 상태 변화 시 교환되는 링크 상태 광고 정보 | 교통 상황 방송 |
| ABR | 서로 다른 Area를 연결하여 라우팅 정보를 요약/필터링하는 경계 라우터 | 도계 톨게이트 |

> 요약: Area 분할과 ABR의 경로 요약을 통해 네트워크 확장성과 라우팅 효율을 보장함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 네이버맺기| -> | LSA 교환 | -> | LSDB 동기| -> | SPF 계산 |
+----------+    +----------+    +----------+    +----------+
```
1. 네이버맺기: 인접 라우터와 Hello 패킷을 교환하여 Adjacency(인접성) 관계 수립
2. LSA 교환: 상태 정보가 담긴 LSA 패킷을 신뢰성 있게 플러딩
3. LSDB 동기: 수신한 LSA를 기반으로 Area 내 모든 라우터가 동일한 토폴로지 맵 유지
4. SPF 계산: Dijkstra 알고리즘을 구동하여 목적지별 최단 경로 라우팅 테이블(FIB) 생성

> 요약: 인접 라우터 발견부터 토폴로지 동기화 및 자체 최단 경로 연산까지 순차 수행함

## Ⅳ. 문제점
- 모든 Area가 Backbone(Area 0)에 물리적 종속되어 분절 발생 시 전체 라우팅 단절 원인
- 특정 링크의 잦은 Up/Down(Flapping) 시 대량의 LSA 폭주로 CPU와 대역폭 고갈
- 불필요한 외부망 정보(LSA Type 5)가 말단 Area까지 전달되어 라우터 메모리 낭비

## Ⅴ. 개선방안
- [단기] ABR에서 Route Summarization(경로 요약)을 적용하여 LSA 테이블 크기 최소화
- [중기] 말단 영역을 Stub 또는 NSSA로 구성하여 불필요한 외부 경로(Type 4/5) 유입 차단
- [장기] OSPFv3 및 가상 링크(Virtual Link) 다중화 설계를 통한 백본 단일 장애 회피

## Ⅵ. 전망
- SDN 기반의 중앙 통제형 경로 제어 체계가 도입되며 OSPF의 토폴로지 관리 역할이 분산될 전망임
