## 미리 알고가기

- ECU는 엔진, 제동, 차체 기능을 제어하는 전자 제어 장치임
- 중재 ID는 여러 ECU가 동시에 전송하려 할 때 우선순위를 정하는 식별자임
- 비파괴 중재는 충돌이 나더라도 우선순위가 낮은 노드만 전송을 멈추고 높은 우선순위 프레임은 계속 지나가게 하는 방식임
- CAN FD는 기존 CAN보다 더 큰 데이터 길이와 빠른 데이터 구간 속도를 지원하는 확장 규격임

## Ⅰ. 개요

- **정의/개념**: CAN 버스는 여러 ECU가 하나의 공용 버스를 공유하면서 메시지 ID 우선순위로 충돌 없이 통신하는 차량 제어 네트워크임
- **배경/필요성**: 차량 기능이 늘어날수록 ECU를 각각 1:1로 연결하면 배선 무게와 복잡도와 고장 지점이 급증하므로 하나의 버스에서 우선순위 기반 통신을 처리할 구조가 필요함

## Ⅱ. 특징

- 메시지 중심 통신이라 수신자가 주소가 아니라 필요한 ID를 기준으로 데이터를 봄
- 비파괴 중재 덕분에 중요한 제어 프레임이 먼저 지나갈 수 있음
- 오류 검출과 자동 재전송으로 차량 환경의 잡음에 강함
- 페이로드가 작고 대역폭이 제한돼 대용량 데이터에는 맞지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | LIN | CAN | 자동차 이더넷 |
|:---|:---|:---|:---|
| 구조 | 저속 단일 마스터 구조임 | 다중 마스터 버스 구조임 | 스위치 기반 IP 통신 구조임 |
| 속도와 용량 | 저속 제어에 적합함 | 일반 차량 제어에 널리 맞음 | 대역폭이 크고 서비스 확장성이 높음 |
| 우선순위 제어 | 단순 스케줄 기반임 | ID 기반 중재를 수행함 | 별도 QoS 정책이 필요함 |
| 대표 활용 | 단순 창문, 좌석 제어 | 파워트레인, 차체 제어 | ADAS, 인포테인먼트, 서비스 통신 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ECU 노드 | 센서 입력을 처리하고 필요한 메시지를 송수신함 |
| CAN 컨트롤러와 트랜시버 | 버스 중재와 프레임 생성과 물리 신호 변환을 담당함 |
| 버스 선로 | 여러 ECU가 공유하는 공용 통신 경로임 |
| 메시지 ID | 우선순위와 의미를 함께 나타내는 핵심 식별자임 |
| 오류 처리 기능 | CRC와 오류 프레임과 자동 재전송으로 통신 안정성을 높임 |

```text
+--------+    +----------------+    +--------+    +--------+
| ECU A  | -- | 공용 CAN 버스    | -- | ECU B  | -- | ECU C  |
+--------+    +----------------+    +--------+    +--------+
          \________ ID 우선순위 기반 중재 ________/
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 버스 유휴 확인  | -> | 중재 시작      | -> | 메시지 전송    | -> | 수신 확인      | -> | 오류 시 재전송 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **버스 유휴 확인**: 전송하려는 ECU가 버스가 비어 있는지 확인함
2. **중재 시작**: 여러 ECU가 동시에 시작하면 더 높은 우선순위 ID가 남음
3. **메시지 전송**: 승리한 ECU가 데이터 프레임을 끝까지 보냄
4. **수신 확인**: 필요한 ECU가 메시지를 읽고 확인 비트를 반영함
5. **오류 시 재전송**: 오류가 감지되면 현재 프레임을 취소하고 다시 보냄

## Ⅵ. 실무 적용 및 유의점

1. 제동이나 조향처럼 지연에 민감한 메시지는 우선순위를 높게 배치해야 하므로 버스 부하율과 메시지 응답 시간을 함께 보며 ID 설계를 검증해야 함
2. 차세대 차량은 데이터량이 늘어 CAN만으로 버티기 어려우므로 제어 영역은 CAN을 유지하되 대용량 구간은 이더넷으로 분리하고 게이트웨이 지연과 오류 프레임 빈도를 확인해야 함

## Ⅶ. 결론

CAN 버스의 핵심은 단순 배선 절감이 아니라 중요한 제어 메시지를 공용 버스에서 우선적으로 안전하게 전달하는 구조에 있음
