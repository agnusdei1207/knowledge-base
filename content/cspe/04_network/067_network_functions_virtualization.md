## 미리 알고가기

- VNF는 방화벽, 라우터, 로드밸런서 같은 네트워크 기능을 가상머신이나 소프트웨어로 구현한 형태임
- NFVI는 VNF가 실행될 컴퓨팅, 스토리지, 네트워크 자원을 제공하는 인프라임
- MANO는 가상 네트워크 기능의 배치와 확장, 종료를 관리하는 체계임
- CNF는 컨테이너 기반으로 구현한 네트워크 기능임

## Ⅰ. 개요

- **정의/개념**: NFV는 전용 네트워크 장비가 수행하던 기능을 범용 서버 위의 가상머신이나 컨테이너로 옮겨 소프트웨어 형태로 운영하는 구조임
- **배경/필요성**: 전용 장비 중심 구조는 기능과 하드웨어 수명주기가 결합되므로 범용 자원 위에서 네트워크 기능 인스턴스를 배치·증설·교체할 구조가 필요함

## Ⅱ. 특징

- 네트워크 기능을 하드웨어에서 분리해 범용 서버 자원 위에서 유연하게 배치할 수 있음
- 기능 증설과 축소를 소프트웨어 배포 방식으로 처리해 서비스 민첩성을 높일 수 있음
- MANO를 통해 배포, 확장, 복구 같은 수명주기 자동화가 가능함
- 고성능 패킷 처리에서는 전용 장비보다 튜닝과 가속 기술이 더 중요해질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전용 네트워크 장비 방식 | NFV 방식 |
|:---|:---|:---|
| 기능 배치 | 기능마다 별도 하드웨어 장비를 도입함 | 범용 서버 위에 필요한 기능을 가상으로 띄움 |
| 확장 방식 | 장비 구매·설치로 처리 용량을 늘림 | 가용 컴퓨팅 자원에 VNF·CNF 인스턴스를 추가함 |
| 비용 구조 | 초기 설비 투자와 교체 비용이 큼 | 범용 자원 재사용으로 유연성이 높지만 운영 플랫폼이 필요함 |
| 성능 특성 | 전용 ASIC의 고정 패킷 처리 경로를 사용함 | 범용 CPU 경로는 DPDK·SR-IOV 설정에 따라 처리량이 달라짐 |

> 요약: NFV는 장비 조달 속도를 소프트웨어 배포 속도로 바꾸지만 성능 튜닝 책임도 함께 가져옴.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VNF·CNF | 방화벽, 라우터, EPC, 5G 코어 기능을 소프트웨어 단위로 구현한 요소임 |
| NFVI | 컴퓨팅, 가상화, 스토리지, 네트워크 자원을 제공하는 실행 기반임 |
| MANO | 서비스 체인 배치, 스케일링, 장애 복구를 관리하는 오케스트레이션 계층임 |
| OSS·BSS 연계 | 운영, 과금, 서비스 주문 정보를 NFV 수명주기와 연결하는 계층임 |
| 가속과 관측 기능 | DPDK, SR-IOV, 텔레메트리 같은 성능 보완과 상태 수집 기능임 |

```text
+-------------+     +----------------+     +----------------+     +----------------+
| OSS·BSS      | --> | MANO            | --> | VNF·CNF         | --> | NFVI           |
+-------------+     +----------------+     +----------------+     +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| 서비스 요청    | --> | 자원 배치 결정     | --> | 기능 인스턴스 생성   | --> | 체인 연결·확장     |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **서비스 요청**: 필요한 네트워크 기능과 용량 요구사항을 입력함
2. **자원 배치 결정**: MANO가 사용 가능한 NFVI 자원을 기준으로 배치 위치를 결정함
3. **기능 인스턴스 생성**: 필요한 VNF나 CNF를 생성하고 초기 설정을 적용함
4. **체인 연결과 확장**: 트래픽 흐름에 맞춰 기능을 연결하고 부하 변화에 따라 확장하거나 종료함

## Ⅵ. 실무 적용 및 유의점

1. 5G 코어, 가상 방화벽, 가상 CPE처럼 기능을 빠르게 늘려야 하는 환경에서는 NFV가 효과적이지만 범용 서버 성능이 부족하면 패킷 처리 병목이 생기므로 DPDK, SR-IOV 같은 가속 옵션을 함께 검토하고 처리량과 CPU 사용률로 확인함
2. 여러 VNF를 서비스 체인으로 묶는 환경에서는 기능 생성보다 수명주기 관리가 더 자주 문제되므로 MANO와 운영 시스템 연계를 먼저 정리하고 인스턴스 생성 시간과 장애 복구 시간을 기준으로 확인함

## Ⅶ. 결론

NFV의 본질은 네트워크 기능을 하드웨어 자산에서 소프트웨어 자원으로 바꾸는 데 있으므로 민첩성 확보와 함께 성능 가속과 운영 자동화가 함께 가야 함.
