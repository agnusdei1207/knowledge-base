# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: VLAN(Virtual LAN)은 **L2 스위치**의 포트를 논리적으로 분할하여 독립된 **브로드캐스트 도메인**을 구성하는 기술이며, 분할된 VLAN 트래픽을 스위치 간 하나의 물리 링크로 전송하는 포트가 Trunk임.
- **왜 필요한가**: 단일 스위치에 모든 단말을 연결하면 ARP·DHCP 등 브로드캐스트가 전체 포트로 퍼져 대역폭 낭비·보안 취약이 발생하나, 부서별로 물리 스위치를 분리하면 장비 비용이 과다함.
- **핵심 직관**: 하나의 넓은 사무실(스위치)에 유리 칸막이(VLAN)를 세워 부서를 나누고, 각 칸막이 사이 우편물은 한 통로(Trunk)로 이동하되 부서 스티커(802.1Q Tag)를 붙여 구분하는 것.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 브로드캐스트 도메인 (상위 키워드) | L2에서 브로드캐스트 프레임이 도달하는 범위 | 방 안에서 소리가 들리는 범위 |
| VLAN (Virtual LAN) | 물리 스위치를 논리적으로 분리한 가상 LAN | 칸막이로 나눈 사무실 |
| Access Port | 단말(PC·서버)과 연결되는 포트, 단일 VLAN만 수용 | 한 부서 전용 출입문 |
| Trunk Port | 스위치 간 다수 VLAN 트래픽을 하나의 링크로 전송하는 포트 | 여러 부서 우편물을 싣는 배달 트럭 |
| 802.1Q Tag (4B) | 이더넷 프레임의 Src MAC 뒤에 삽입되는 VLAN 식별 필드(VLAN ID 12비트, 최대 4,094개) | 택배 상자의 부서 스티커 |
| Native VLAN | Trunk 링크에서 태그 없이 전송되는 기본 VLAN(기본값 VLAN 1) | 스티커 없는 우편물이 도착하는 기본 부서 |
| PVID (Port VLAN ID) | Access 포트에 할당된 VLAN 번호 | 출입문에 붙은 부서 번호 |
| DTP (Dynamic Trunking Protocol) | 스위치 간 Trunk를 자동 협상하는 Cisco 프로토콜 | 자동 도로 개설 — 보안 취약점 |

## 깊이 이해
- **배경·문제의식**: 이더넷 프레임 구조(018 참조)에서 브로드캐스트(Dst MAC = FF:FF:FF:FF:FF:FF)는 스위치의 모든 포트로 복제 전달됨. PC 수백~수천 대가 하나의 브로드캐스트 도메인에 있으면 ARP 요청만으로도 대역폭의 상당 부분이 소모되고, 스위치 CPU가 포화되어 브로드캐스트 스톰이 발생함.
- **작동 원리 — Access Port**: 스위치 관리자가 포트 1~10번에 VLAN 10(영업팀), 포트 11~20번에 VLAN 20(개발팀)을 할당하면, 각 포트로 인입된 프레임은 해당 VLAN의 MAC 테이블에서만 검색됨. VLAN 10의 브로드캐스트는 VLAN 20 포트로 전달되지 않으므로, 물리적으로 같은 스위치에 꽂혀 있어도 완전한 논리적 격리가 이뤄짐.
- **작동 원리 — Trunk Port**: 스위치 A(VLAN 10, 20 존재)와 스위치 B(VLAN 10, 20 존재)를 연결할 때, VLAN별로 물리 케이블을 따로 연결하면 포트를 낭비함. Trunk는 단일 물리 링크로 모든 VLAN을 전송하되, 프레임이 Trunk 포트로 나갈 때 802.1Q 4바이트 태그를 삽입하고(Push), 상대 스위치가 수신 시 태그를 읽어 해당 VLAN으로 분류한 뒤 제거(Pop)함.
- **비유**: 부서가 5개인 본사와 지사를 연결할 때, 부서별 전용 도로 5개가 아니라 택배 트럭(Trunk) 1대에 부서 스티커(Tag)를 붙인 상자를 함께 실어 보내는 것.
- **구체 예시**: IP 전화기(Voice VLAN 50)와 PC(Data VLAN 10)를 스위치의 같은 포트에 연결할 때, 스위치는 Access VLAN 10으로 PC 트래픽을, Voice VLAN 50으로 음성 트래픽을 태그 기반으로 분리 처리함. 이때 프레임 크기는 802.1Q 태그로 인해 1518B에서 1522B로 증가함(018 참조).
- **흔한 오해·주의점**: VLAN은 L2 수준의 격리이므로 VLAN 간 통신은 반드시 L3 장비(라우터 또는 L3 스위치의 SVI)를 거쳐야 함. 또 Native VLAN(기본 VLAN 1)은 태그 없이 전송되므로 이중 태깅(Double Tagging) 공격에 취약함 — DTP 비활성화와 Native VLAN 번호 변경이 필수 보안 조치임.

## 연결 개념
- **이더넷 프레임(018)**: 802.1Q 태그는 이더넷 프레임의 Src MAC 뒤에 4B를 삽입하는 확장 구조임.
- **STP/RSTP(020)**: VLAN별 루프 방지를 위해 PVST+/MSTP가 VLAN 단위 스패닝 트리를 구성함.
- **VXLAN(069)**: 802.1Q의 VLAN ID 4,094개 한계를 L3 오버레이로 극복(최대 1,600만 개).

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 물리적 1대의 L2 스위치를 논리적으로 다수의 브로드캐스트 도메인으로 분할하는 기술임.
> 2. **가치**: 브로드캐스트 도메인 축소로 대역폭을 절약하고, 부서·서비스 간 L2 격리로 보안 경계를 구현함.
> 3. **판단 포인트**: Access/Trunk 포트의 802.1Q 태깅 동작 차이, Native VLAN 보안 취약점 통제, VLAN ID 4,094개 상한의 확장(VXLAN)이 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| L2 환경에서 논리적 망 분리와 Trunk 연결 원리 | 802.1Q 4B 태그 삽입 위치·VLAN ID 12비트, Access vs Trunk 동작 차이 | 프레임 관점 태깅 과정 누락, VLAN 간 통신에 L3 필요 미언급 |

> 요약: 포트별 VLAN 할당(Access)과 다중 VLAN 전송(Trunk, 802.1Q)을 프레임 수준에서 구분하고, 보안 취약점(DTP·Native VLAN)까지 서술해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 물리 배치와 무관하게 논리적 브로드캐스트 도메인을 구성하는 L2 스위칭 분할 기술임.
- 배경: 단일 평면(Flat) 네트워크에서 단말 증가 시 브로드캐스트 트래픽 폭증으로 대역폭 낭비·스위치 CPU 포화 발생함.
- 필요성: 물리 스위치 추가 없이 부서·용도별 보안 격리, 브로드캐스트 도메인 축소(수백→수십 단말 단위), 유연한 토폴로지 변경이 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
PC-A(VLAN 10) -> [Access Port] -> 스위치 1 -> [Trunk Port / 802.1Q] -> 스위치 2 -> [Access Port] -> PC-B(VLAN 10)
                                      |                                     |
PC-C(VLAN 20) -> [Access Port] ------+                                     +-> [Access Port] -> PC-D(VLAN 20)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Access Port | 단말이 연결되는 포트, 단일 VLAN 트래픽만 수용 | Untagged — 프레임에 태그를 붙이지 않음 |
| Trunk Port | 스위치 간 다수 VLAN 트래픽을 단일 물리 링크로 전송 | 802.1Q Tag 삽입(Push)·제거(Pop) |
| 802.1Q Tag (4B) | Src MAC 뒤에 삽입, VLAN ID(12비트, 최대 4,094개) 식별 | TPID(0x8100) + PCP(3비트 우선순위) + DEI + VID |
| Native VLAN | Trunk에서 태그 없이 전송되는 기본 VLAN(기본 VLAN 1) | 이중 태깅 공격 경로 — 비사용 번호로 변경 필수 |

> 요약: 단말-스위치 간(Access)은 순수 이더넷 프레임, 스위치 간(Trunk)은 802.1Q 태그로 VLAN을 식별하여 다중 전송함.

---

## Ⅲ. 동작원리 및 흐름도

```text
단말 프레임 송신 -> Access 포트 인입(PVID 부여) -> MAC 테이블 조회(동일 VLAN 내) -> Trunk 출력(802.1Q Tag Push) -> 대향 스위치 수신(Tag Pop) -> Access 포트 출력
```

1. Access 포트 수신: 인입 프레임에 해당 포트의 PVID(Port VLAN ID)를 내부적으로 부여하여 VLAN 소속을 결정함.
2. MAC 테이블 조회: 동일 VLAN 내의 MAC 주소만 검색하며, 다른 VLAN의 MAC은 참조하지 않아 L2 격리가 성립함.
3. Trunk 포트 출력(태깅): 프레임이 Trunk 포트로 나갈 때 Src MAC 뒤에 4B 802.1Q 헤더를 삽입하고 CRC를 재계산함.
4. 대향 스위치 수신·출력: 수신 스위치가 태그의 VID를 읽어 VLAN을 식별하고, 태그를 제거(Pop)한 뒤 해당 VLAN의 Access 포트로 전달함.

> 요약: 스위치는 내부적으로 PVID 기반 VLAN 분류를 수행하고, Trunk에서는 802.1Q 태그 Push/Pop으로 다중 VLAN 트래픽을 단일 링크에 다중화함.

---

## Ⅳ. 특징

- 브로드캐스트 격리: VLAN이 다르면 MAC 테이블 공간이 분리되어 ARP·DHCP 브로드캐스트가 해당 VLAN 내로 한정됨.
- L2 수준 완전 단절: 서로 다른 VLAN 간 통신은 L3 스위치(SVI)나 라우터의 Inter-VLAN 라우팅을 거쳐야 하므로 ACL 기반 접근 제어 포인트가 됨.
- 802.1Q 프레임 확장: 4B 태그 삽입으로 프레임 최대 크기가 1518B에서 1522B로 증가하며, PCP 3비트로 CoS 우선순위를 부여할 수 있음.
- VLAN ID 한계: 12비트 VID로 최대 4,094개(0·4095 예약)까지만 지원하여, 대규모 멀티 테넌트 환경에서는 VXLAN(24비트, 1,600만 개)으로 확장이 필요함.

> 요약: VLAN은 L2 수준의 완전 격리를 제공하며, 부서 간 통신이 필요할 때만 L3를 통해 통제된 연결을 허용함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Port-based VLAN(정적) | MAC-based VLAN(동적) | 선택 기준 |
|:---|:---|:---|:---|
| 할당 기준 | 스위치의 물리 포트 번호 | 단말의 MAC 주소(VMPS 서버) | 단말 이동성 요구 수준 |
| 관리 용이성 | 직관적·간단, 엔터프라이즈 90%↑ 사용 | VMPS 서버 별도 운영 필요 | 운영 오버헤드 허용 범위 |
| 이동성 | 자리 변경 시 포트 재설정 필요 | 자리 이동해도 동일 VLAN 자동 유지 | 무선·핫데스킹 환경 여부 |

> 요약: 대부분의 유선 환경은 포트 기반 VLAN을 쓰며, 무선·802.1X 인증 환경에서만 동적 VLAN을 제한적으로 적용함.

**리스크·대응:**
- VLAN Hopping 공격: DTP 자동 협상을 악용해 공격자가 Trunk 포트로 위장 → `switchport nonegotiate` 명령으로 DTP 비활성화 (지표: Trunk 포트 협상 로그)
- Native VLAN 이중 태깅: 기본 VLAN 1의 태그 미삽입을 악용한 Double Tagging 공격 → Native VLAN을 미사용 번호(예: 999)로 변경, Trunk에서 native 태깅 강제 (지표: VLAN 1 트래픽 유입량)

**점검 지표:**
- 보안: 미사용 포트의 VLAN 할당 현황 — 미할당 포트는 비활성화(shutdown) 또는 격리 VLAN으로 설정
- 성능: VLAN별 브로드캐스트 비율 — 전체 트래픽 대비 브로드캐스트 5% 이하 유지 목표

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 보안망 분리: 콜센터에서 고객 정보망(VLAN 10)과 일반 인터넷망(VLAN 20)을 포트 기반으로 격리하고, L3에서 Inter-VLAN 라우팅을 차단하여 물리 분리에 준하는 논리 격리 구현.
2. 음성/데이터 통합: IP 전화기 도입 시 Data VLAN(10)과 Voice VLAN(50)을 동일 포트에 할당하고, PCP 우선순위로 음성 QoS를 보장함.
3. 가상화 연동: VMware ESXi 호스트 연결 포트를 802.1Q Trunk로 설정하고 `allowed vlan` 명령으로 필요 VLAN만 허용하여, 불필요한 브로드캐스트 유입을 차단함.

**결론:**
- 기술사 판단: 유선 LAN 환경에서는 포트 기반 VLAN으로 브로드캐스트 도메인을 축소하고 L3 ACL로 접근을 통제하며, 무선·모바일 환경에서는 802.1X 기반 동적 VLAN을 병행 적용함.
- 향후 방향: 멀티 테넌트 클라우드 환경에서 802.1Q의 VLAN ID 4,094개 한계를 극복하기 위해 VXLAN(24비트 VNI, 1,600만 개)·EVPN 기반 L3 오버레이로 전환이 확산됨.
