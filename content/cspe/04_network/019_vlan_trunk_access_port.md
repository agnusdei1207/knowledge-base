## 미리 알고가기

- VLAN: 하나의 물리 스위치를 여러 개의 논리 네트워크처럼 나눠 쓰는 기술임
- 브로드캐스트 도메인: 같은 방송 프레임이 도달하는 범위임
- 액세스 포트: 하나의 VLAN에만 연결되는 단말용 포트임
- 트렁크 포트: 여러 VLAN 트래픽을 802.1Q 태그와 함께 전달하는 포트임
- Native VLAN: 트렁크에서 태그 없는 프레임을 처리할 때 사용하는 VLAN임

## Ⅰ. 개요

- **정의/개념**: VLAN은 스위치 포트를 논리적으로 나눠 브로드캐스트 도메인을 분리하는 기술이며, 액세스 포트는 단일 VLAN 단말을 연결하고 트렁크 포트는 여러 VLAN을 운반함
- **배경/필요성**: 단말 수가 많아질수록 브로드캐스트 범위와 보안 경계가 커지므로 부서와 서비스 단위로 망을 나누고 필요한 링크만 연결하는 구조가 필요함

## Ⅱ. 특징

- VLAN은 물리 위치와 별개로 단말을 논리적으로 묶어 브로드캐스트 범위를 줄임
- 액세스 포트는 태그 없는 단말 연결에 적합하고 송신 시 보통 태그를 제거함
- 트렁크 포트는 802.1Q 태그로 여러 VLAN 프레임을 하나의 링크에 함께 실음
- 서로 다른 VLAN 간 통신은 L2 스위칭만으로 되지 않으며 L3 라우팅이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 액세스 포트 | 트렁크 포트 |
|:---|:---|:---|
| 연결 대상 | PC, 프린터, 서버처럼 하나의 VLAN에 속한 단말을 연결함 | 스위치, 라우터, 가상화 호스트처럼 여러 VLAN을 운반하는 장비를 연결함 |
| 프레임 처리 | 수신 프레임을 특정 VLAN에 귀속시키고 송신 시 태그를 제거함 | 프레임에 802.1Q 태그를 붙이거나 유지해 VLAN을 구분함 |
| 운영 장점 | 단말 설정이 단순하고 포트별 소속 확인이 쉬움 | 링크 수를 늘리지 않고 여러 VLAN을 전달함 |
| 주의할 점 | 잘못된 VLAN 할당은 해당 단말 단절로 이어짐 | 허용 VLAN과 Native VLAN 설정이 틀리면 누락이나 우회가 발생함 |

> 요약: 액세스 포트는 단말 소속을 정하고, 트렁크 포트는 VLAN 태그를 이용해 여러 논리망을 링크 하나로 운반함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VLAN ID | 프레임이 어떤 논리 네트워크에 속하는지 식별하는 값임 |
| Access Port | 특정 VLAN에 포트를 고정해 단말이 태그를 몰라도 통신할 수 있게 함 |
| Trunk Port | 여러 VLAN을 동시에 싣기 위해 태그가 붙은 프레임을 통과시킴 |
| Inter-VLAN Routing | 서로 다른 VLAN 사이 통신을 처리하는 L3 기능이며 SVI나 라우터가 맡음 |

```text
+--------+      +-----------+      +-----------+      +--------+
| Host A | ---> | Access V10| ---- | Trunk V10 | ---> |Switch B|
+--------+      +-----------+      +-----------+      +--------+
```

> 요약: VLAN 구조는 단말이 붙는 액세스 포트와 VLAN을 운반하는 트렁크 포트가 함께 맞아야 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| VLAN할당  | --> | 태그부여  | --> | 링크전달  | --> | 태그제거 |
+----------+     +----------+     +----------+     +----------+
```

1. **VLAN할당**: 단말이나 서비스에 맞는 VLAN ID를 포트에 할당함
2. **태그부여**: 트렁크 구간에 들어갈 때 프레임에 802.1Q 태그를 붙임
3. **링크전달**: 트렁크 링크가 여러 VLAN 프레임을 함께 전달함
4. **태그제거**: 목적지 액세스 포트에서 단말이 이해할 수 있게 태그를 제거하고 내보냄

## Ⅵ. 실무 적용 및 유의점

1. 캠퍼스망에서는 기본 Native VLAN을 그대로 두면 홉핑과 오배선 위험이 커지므로 허용 VLAN 목록을 줄이고 Native VLAN 변경 여부와 브로드캐스트 비율로 확인함
2. 서버 가상화 환경에서는 하이퍼바이저와 스위치의 트렁크 허용 목록이 다르면 특정 서비스만 단절되므로 VLAN별 통신 성공률과 MAC 학습 상태로 확인함

## Ⅶ. 결론

VLAN 설계의 판단 기준은 브로드캐스트 범위를 나누고 액세스와 트렁크 구간의 태그 처리를 일치시키는 데 있음.

## 작성 근거(검토용)

- VLAN은 망 분리라는 넓은 표현보다 브로드캐스트 범위, 태그 처리, Inter-VLAN Routing으로 설명해야 정확하므로 그 기준으로 전개함
- 링크 사용 판단은 링크 수 절감과 허용 VLAN 확인처럼 구체 운영 기준으로 바꿈
- 결론은 액세스와 트렁크의 절차 차이를 회수함
