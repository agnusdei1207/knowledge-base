# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 물리적 스위치 하나를 여러 개의 가상 스위치로 나누어 사용하는 **논리적 망 분리 기술**입니다.
- **필요성**: 모든 컴퓨터가 한 스위치에 있으면 방송(Broadcast) 메시지가 너무 많아져 느려지고 보안도 취약해집니다. 부서별로 가상의 벽을 세워 트래픽을 격리해야 합니다.
- **핵심 직관**: **"하나의 사무실에 칸막이 치기"**. 같은 사무실에 있어도 칸막이 너머 소리(브로드캐스트)는 들리지 않게 하는 것과 같습니다.

## 깊이 이해
- **배경 (브로드캐스트 도메인의 분리)**: 네트워크에 기기가 많아지면 ARP 같은 브로드캐스트 패킷이 폭증하여 성능을 갉아먹습니다. VLAN을 쓰면 물리적 위치와 상관없이 '영업팀', '개발팀' 등 논리적으로 네트워크를 쪼갤 수 있습니다.
- **작동 원리 (Access vs Trunk)**:
  - **Access Port**: 특정 VLAN 하나에만 속하는 포트. 주로 PC나 프린터가 연결됩니다. (태그가 없는 일반 프레임 전송)
  - **Trunk Port**: 여러 VLAN의 데이터를 한 번에 실어 나르는 통로. 스위치와 스위치 사이를 연결할 때 씁니다. (어느 VLAN 데이터인지 표시하는 **802.1Q 태그**를 붙여서 전송)
- **802.1Q Tagging**: 이더넷 프레임 안에 "이 데이터는 10번 VLAN 거야"라고 적힌 4바이트짜리 이름표를 끼워 넣는 표준 방식입니다.
- **비유 (아파트 엘리베이터)**:
  - **Access**: 우리 집 현관문. 우리 가족(특정 VLAN)만 드나듦.
  - **Trunk**: 아파트 엘리베이터. 여러 층(VLAN) 사람들이 같이 타지만, 각자 내리는 층(VLAN ID)이 정해져 있음.

## 연결 개념
- **Inter-VLAN Routing**: VLAN끼리 서로 대화하려면 3계층 장비(L3 스위치나 라우터)가 필요합니다. (L2에서는 절대 못 넘어감)
- **Native VLAN**: 트렁크 포트에서 태그 없이 다니는 기본 VLAN. 보안을 위해 보통 1번 대신 다른 번호로 바꿉니다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: L2 스위치 포트를 논리적으로 그룹화하여 물리적 위치와 관계없이 독립된 브로드캐스트 도메인을 구성하는 기술임.
> 2. **가치**: 브로드캐스트 트래픽 국지화를 통해 대역폭 효율을 높이고, 부서/서비스 간 L2 수준의 격리를 통해 보안성을 강화함.
> 3. **판단 포인트**: 다중 VLAN 트래픽 전송을 위한 802.1Q 트렁킹 프로토콜과 VLAN 간 통신을 위한 L3 라우팅(Inter-VLAN) 설계가 핵심임.

## Ⅰ. VLAN의 정의 및 주요 이점
- **정의**: 물리적 LAN을 논리적으로 분할하여 별도의 서브넷처럼 동작하게 하는 기술 (IEEE 802.1Q 표준).
- **주요 이점**:
  - **브로드캐스트 제어**: 브로드캐스트 도메인을 축소하여 네트워크 성능 최적화.
  - **보안성 강화**: 민감한 부서 트래픽을 물리적 변경 없이 논리적으로 격리.
  - **유연한 관리**: 조직 개편이나 자리 이동 시 배선 공사 없이 소프트웨어 설정만으로 네트워크 변경 가능.

## Ⅱ. VLAN 포트 유형 및 동작 메커니즘

### 1. 액세스 포트 (Access Port)
- 하나의 VLAN에만 고정적으로 할당된 포트.
- 최종 단말(PC, Server) 연결 시 사용.
- **동작**: 프레임 전송 시 VLAN 태그를 제거하고 보냄 (Untagged).

### 2. 트렁크 포트 (Trunk Port)
- 다수의 VLAN 트래픽을 하나의 물리 링크로 동시에 전송하는 포트.
- 스위치 간 연결, 혹은 라우터(Router-on-a-stick) 연결 시 사용.
- **동작**: 프레임마다 VLAN ID를 식별할 수 있는 **802.1Q Tag**를 삽입 (Tagged).

## Ⅲ. IEEE 802.1Q 프레임 태깅 구조 (4 Byte)

| 필드명 | 비트수 | 설명 |
|:---:|:---:|:---|
| **TPID** | 16 bit | 태그된 프레임임을 표시 (0x8100) |
| **PCP (Priority)** | 3 bit | L2 계층의 우선순위(CoS) 표시 (0~7) |
| **DEI (CFI)** | 1 bit | 토큰링 등과의 호환성 및 폐기 적격성 표시 |
| **VLAN ID (VID)** | **12 bit** | VLAN 식별 번호 (**총 4,096개 생성 가능**) |

## Ⅳ. VLAN 간 통신 (Inter-VLAN Routing)

### 1. Router-on-a-stick
- 하나의 물리적 라우터 인터페이스를 여러 개의 논리적 서브 인터페이스로 나누어 VLAN 간 라우팅 수행.
- 구조는 단순하나 트렁크 링크가 병목(Bottleneck)이 될 수 있음.

### 2. L3 스위치 (SVI 활용)
- 스위치 내부의 **SVI(Switch Virtual Interface)**를 생성하여 하드웨어 속도로 VLAN 간 라우팅 수행.
- 현대 네트워크 환경에서 가장 선호되는 방식.

## Ⅴ. VLAN 보안 및 설계 고려사항

### 1. Native VLAN 보안
- 태그 없는 프레임을 처리하는 Native VLAN(기본값 1번)을 통해 'VLAN Hopping' 공격 발생 가능.
- **대응**: Native VLAN 번호를 임의의 번호로 변경하고, 트렁크에서 강제 태깅(Tag Native) 설정.

### 2. VLAN Pruning (가지치기)
- 트렁크 링크에서 실제로 해당 스위치에 존재하지 않는 VLAN 트래픽은 차단하여 불필요한 트래픽 낭비 방지.

## Ⅵ. 기술사적 통찰: '물리'의 한계를 넘는 '가상'
- **SDN으로의 확장**: 전통적인 VLAN은 4,096개라는 ID 한계가 있음. 이를 극복하기 위해 클라우드 데이터센터에서는 **VXLAN**(24비트 ID, 1,600만 개) 같은 터널링 기술로 발전함.
- **마이크로 세그멘테이션**: 과거에는 부서 단위(VLAN)로 격리했다면, 이제는 제로 트러스트 관점에서 서버 한 대, 앱 하나 단위로 격리하는 정교한 정책 제어가 트렌드임.
- **결론**: VLAN은 네트워크 가상화의 효시이자 가장 성공적인 기술이며, 효율적인 네트워크 인프라 구축을 위한 **"가장 기본적이고 강력한 도구"**임.
