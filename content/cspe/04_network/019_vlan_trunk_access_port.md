## 미리 알고가기

- VLAN: 하나의 물리 스위치를 여러 개의 논리 네트워크처럼 나눠 쓰는 기술임
- 브로드캐스트 도메인: 같은 방송 프레임이 도달하는 범위임
- 액세스 포트: 하나의 VLAN에만 연결되는 단말용 포트임
- 트렁크 포트: 여러 VLAN 트래픽을 태그와 함께 실어 나르는 포트임

## Ⅰ. 개요

- **정의/개념**: VLAN은 물리 배선은 그대로 둔 채 스위치 포트를 논리적으로 묶어 여러 개의 브로드캐스트 도메인으로 나누는 기술임. 액세스 포트는 단일 VLAN 단말을 연결하고, 트렁크 포트는 여러 VLAN 트래픽을 동시에 전달함
- **배경/필요성**: 단말 수가 많아질수록 브로드캐스트 범위와 보안 경계가 함께 커지므로, 부서와 서비스 단위로 망을 나누고 필요한 구간만 연결하는 구조가 필요함

## Ⅱ. 특징

- VLAN은 물리 위치와 상관없이 논리적으로 단말을 묶을 수 있어 망 분리와 관리가 쉬움
- 액세스 포트는 태그 없는 단말 연결에 적합하고, 트렁크 포트는 스위치 간 다중 VLAN 전달에 적합함
- 802.1Q 태그를 이용하면 하나의 링크로 여러 VLAN을 실을 수 있어 링크 사용 효율이 높아짐
- VLAN을 나누기만 해서는 통신이 되지 않으므로 서로 다른 VLAN 간 통신은 반드시 L3 장비가 처리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 액세스 포트 | 트렁크 포트 |
|:---|:---|:---|
| 연결 대상 | PC, 프린터, 서버처럼 하나의 VLAN에 속한 단말을 연결함 | 스위치, 라우터, 가상화 호스트처럼 여러 VLAN을 동시에 운반하는 장비를 연결함 |
| 프레임 처리 | 수신 프레임을 특정 VLAN에 귀속시키고 송신 시에는 보통 태그를 제거함 | 송수신 프레임에 802.1Q 태그를 유지해 어떤 VLAN 소속인지 함께 전달함 |
| 운영 장점 | 단말 설정이 단순하고 오배치 가능성이 낮음 | 링크 수를 줄이면서도 여러 VLAN을 한 번에 연결할 수 있음 |
| 주의할 점 | 잘못된 VLAN 할당은 단말 통신 단절로 바로 이어짐 | 허용 VLAN과 Native VLAN 설정이 틀리면 누락이나 우회가 발생함 |

> 요약: 액세스 포트는 단말 연결용이고, 트렁크 포트는 여러 VLAN을 묶어 전달하는 백본 연결용임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VLAN ID | 프레임이 어떤 논리 네트워크에 속하는지 식별하는 값이며, 이 값이 다르면 브로드캐스트 도메인도 분리됨 |
| Access Port | 특정 VLAN에 포트를 고정해 단말이 별도 태그를 몰라도 통신할 수 있게 함 |
| Trunk Port | 여러 VLAN을 동시에 싣기 위해 태그가 붙은 프레임을 통과시키며 스위치 간 연결의 핵심이 됨 |
| Inter-VLAN Routing | 서로 다른 VLAN 사이 통신을 처리하는 L3 기능이며 SVI나 라우터가 이 역할을 맡음 |

```text
+--------+      +-----------+      +-----------+      +--------+
| Host A | ---> | Access V10| ---- | Trunk V10 | ---> |Switch B|
+--------+      +-----------+      +-----------+      +--------+
```

> 요약: VLAN 구조는 단말이 붙는 액세스 포트와 스위치 간에 VLAN을 운반하는 트렁크 포트가 함께 돌아가야 완성됨

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| VLAN할당 | --> | 태그부여  | --> | 링크전달  | --> | 태그제거  |
+----------+     +----------+     +----------+     +----------+
```

1. **VLAN할당**: 단말이나 서비스에 맞는 VLAN ID를 포트에 할당함
2. **태그부여**: 트렁크 구간에 들어갈 때 프레임에 802.1Q 태그를 붙임
3. **링크전달**: 트렁크 링크가 여러 VLAN 프레임을 함께 전달함
4. **태그제거**: 목적지 액세스 포트에서 단말이 이해할 수 있게 태그를 제거하고 내보냄

## Ⅵ. 실무 적용 및 유의점

1. 캠퍼스망에서는 부서와 보안 구역별로 VLAN을 나누되 기본 Native VLAN을 그대로 두면 홉핑과 오배선 위험이 커지므로 허용 VLAN 목록을 최소화하고 Native VLAN 변경 여부와 브로드캐스트 비율로 확인함
2. 서버 가상화 환경에서는 하나의 업링크에 여러 서비스 VLAN을 태우더라도 인터페이스별 태그 정책이 틀리면 특정 서비스만 단절되므로 하이퍼바이저와 스위치의 트렁크 허용 목록을 맞추고 VLAN별 통신 성공률과 MAC 학습 상태로 확인함

## Ⅶ. 결론

VLAN과 액세스·트렁크 포트 설계의 핵심은 브로드캐스트 범위를 줄이면서 필요한 구간에만 정확히 태그를 실어 보내는 데 있음.
