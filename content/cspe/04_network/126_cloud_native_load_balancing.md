## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 클라우드 환경에서 트래픽을 컨테이너 기반 엔드포인트로 동적 분산하는 기술임 |
| 배경 | 빈번한 파드 생성 및 삭제(Auto-scaling) 환경에 맞는 유연한 라우팅 체계 필요 |
| 출제 | Ingress Controller, Gateway API, L7 로드밸런싱 최적화 |

## Ⅱ. 구성요소
```text
+--------------+        +--------------+        +--------------+
| Client Req   | -----> | Gateway API  | -----> | Endpoints    |
| (External)   | Route  | (Controller) | LB     | (Pod Group)  |
+--------------+        +--------------+        +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 인그레스 | 외부 HTTP/S 트래픽을 클러스터 내부로 라우팅하는 진입점임 | 정문 안내소 |
| 라우팅 규칙 | 도메인(Host) 및 경로(Path) 기반의 L7 분산 정책임 | 이정표 |
| 엔드포인트 | 실제 요청을 처리하는 동적인 파드(Pod) 집합체임 | 작업자 그룹 |

> 요약: 외부 트래픽을 유연한 라우팅 규칙에 따라 K8s 내부 파드로 분산함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Request| -> | 2. Match  | -> | 3. Balance| -> | 4. Forward|
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 요청 (Request): 클라이언트가 클라우드 로드밸런서를 통해 트래픽 전송함.
2. 규칙 매칭 (Match): Ingress 또는 Gateway API 규칙을 기반으로 헤더 분석함.
3. 부하 분산 (Balance): 라운드 로빈 등 알고리즘 기반으로 대상 파드 선정함.
4. 패킷 전달 (Forward): 최종 목적지 엔드포인트로 패킷을 전달하고 응답함.

> 요약: 외부 요청 헤더를 분석하고 적합한 파드로 부하를 동적 분산함.

## Ⅳ. 문제점
- 기능 제약: 기존 Ingress 표준은 복잡한 L7 라우팅 기능 구현에 한계 있음.
- 상태 불일치: 대규모 파드 증감 시 밸런서 설정 동기화 지연 및 트래픽 유실 발생함.
- 벤더 종속: AWS ALB 등 특정 클라우드 벤더의 인그레스 컨트롤러에 종속됨.

## Ⅴ. 개선방안
- Gateway API (단기): 역할 기반의 K8s Gateway API 표준 도입으로 유연성 확보함.
- 동적 동기화 (중기): 컨트롤 루프 최적화를 통해 엔드포인트 갱신 지연 최소화함.
- 오픈소스 활용 (장기): 멀티 클라우드를 지원하는 범용 역방향 프록시 활용함.

## Ⅵ. 전망
- 클라우드 네이티브 로드 밸런싱은 벤더 종속성을 탈피하여 차세대 Gateway API 표준으로 완전히 수렴될 것임.
