## 미리 알고가기

- 슬라이딩 윈도우: 수신 버퍼 여유에 맞춰 연속 전송 범위를 이동시키는 방식임
- Slow Start: 연결 초기에 혼잡 윈도우를 빠르게 키우는 혼잡 제어 시작 단계임
- rwnd: 수신 측이 현재 받을 수 있다고 광고한 양임
- cwnd: 송신 측이 네트워크 혼잡 상태를 보고 스스로 정한 양임

## Ⅰ. 개요

- **정의/개념**: 흐름 제어는 송신 속도가 수신 처리 속도를 넘지 않도록 조절하는 메커니즘이며, 실무 TCP에서는 슬라이딩 윈도우의 `rwnd`와 초기 송신량을 조절하는 `cwnd` 시작 단계가 함께 작동함. 다만 슬라이딩 윈도우는 수신자 보호가 목적이고, Slow Start는 네트워크 혼잡을 피하며 시작 속도를 올리는 절차라는 점을 구분해야 함
- **배경/필요성**: 실제 TCP 송신량은 수신 버퍼 한계와 네트워크 혼잡 한계를 동시에 받으므로, 둘을 분리해 이해하지 않으면 Zero Window와 혼잡 지연을 같은 문제로 오해하기 쉬움

## Ⅱ. 특징

- 슬라이딩 윈도우는 수신 측 버퍼 보호를 위한 흐름 제어의 중심 메커니즘임
- Slow Start는 엄밀히는 혼잡 제어이지만 연결 초기 송신량 형성에 직접 영향을 주므로 함께 출제되기 쉬움
- 실제 송신량은 `rwnd`와 `cwnd` 가운데 더 작은 값에 의해 제한됨
- 문제 원인이 수신자 병목인지 네트워크 병목인지 먼저 나눠야 대응이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 슬라이딩 윈도우 | Slow Start |
|:---|:---|:---|
| 주된 목적 | 수신 측 버퍼가 넘치지 않게 송신량을 제한함 | 연결 초기에 가용 대역폭을 빠르게 탐색함 |
| 기준 값 | 수신 측이 광고한 `rwnd`를 기준으로 동작함 | 송신 측이 정한 `cwnd`와 `ssthresh`를 기준으로 동작함 |
| 병목 해석 | 느린 수신 애플리케이션이나 작은 버퍼가 원인일 때 중요함 | 중간 네트워크 경로의 혼잡 가능성이 원인일 때 중요함 |
| 실무 판단 | Zero Window와 작은 버퍼 광고를 보면 흐름 제어 문제로 봄 | RTT 증가와 손실 후 윈도우 축소를 보면 혼잡 제어 문제로 봄 |

> 요약: 슬라이딩 윈도우와 Slow Start는 둘 다 송신량을 제한하지만, 기준과 보호 대상이 다름

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 수신 버퍼와 rwnd | 수신 측이 현재 얼마나 더 받을 수 있는지 알려 주며 흐름 제어의 기준이 됨 |
| 송신 버퍼 | 아직 전송하지 않았거나 ACK를 받지 못한 데이터를 유지함 |
| cwnd와 ssthresh | 연결 초기에 보낼 수 있는 양과 증가 방식을 바꾸는 시점을 결정함 |
| ACK 피드백 | 어디까지 받았는지와 더 받을 여유가 있는지를 송신 측에 되돌려 줌 |

```text
+--------+     +-----------+     +-----------+     +--------+
| Sender | --> | rwnd/cwnd | --> | ACK 피드백 | --> | Adjust |
+--------+     +-----------+     +-----------+     +--------+
```

> 요약: 실전 TCP 전송량은 수신 버퍼 기반 제어와 네트워크 혼잡 기반 제어가 동시에 반영된 결과임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 초기증가 | --> | 버퍼광고  | --> | 연속전송  | --> | 한계조정  |
+----------+     +----------+     +----------+     +----------+
```

1. **초기증가**: 연결 시작 시 Slow Start로 `cwnd`를 빠르게 키워 초기 전송량을 형성함
2. **버퍼광고**: 수신 측이 `rwnd`를 알려 송신 측에 현재 수용 가능량을 전달함
3. **연속전송**: 송신 측이 `min(rwnd, cwnd)` 범위 안에서 데이터를 연속 전송함
4. **한계조정**: ACK, Zero Window, 손실 신호에 따라 수신자 한계와 네트워크 한계를 각각 반영해 송신량을 조정함

## Ⅵ. 실무 적용 및 유의점

1. 장거리 대용량 전송에서는 수신 버퍼와 Window Scale이 작으면 링크를 못 채우므로 버퍼 크기와 윈도우 확장을 함께 조정하고 처리량과 rwnd 값을 기준으로 확인함
2. 애플리케이션 처리 지연으로 Zero Window가 반복되는 상황을 혼잡 문제로 오해하면 대응이 어긋나므로 수신 처리 지연과 손실 지표를 분리해 보고 Zero Window 이벤트 수와 RTT 변화를 함께 확인함

## Ⅶ. 결론

흐름 제어는 `rwnd`로 수신자 한계를 반영하고, Slow Start는 `cwnd`로 초기 네트워크 투입량을 조절하므로 두 기준을 구분해야 함.
