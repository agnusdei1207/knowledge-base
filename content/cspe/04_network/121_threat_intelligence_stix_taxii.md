## 미리 알고가기

- 위협 인텔리전스는 공격자와 공격 방식과 침해 흔적 정보를 구조화한 보안 지식임
- 지표는 악성 IP, 도메인, 해시처럼 탐지에 바로 쓸 수 있는 단서임
- STIX는 위협 정보를 표준 객체 형태로 표현하는 형식임
- TAXII는 STIX 정보를 주고받는 전송 인터페이스임

## Ⅰ. 개요

- **정의/개념**: STIX와 TAXII는 위협 인텔리전스를 구조화해 표현하고 자동으로 교환하게 만드는 표준 조합으로, STIX는 내용 형식이고 TAXII는 전달 방식임
- **배경/필요성**: 위협 정보를 문서나 메일로만 주고받으면 재사용과 자동 반영이 어렵고 대응 속도도 늦어지므로, 기계가 읽고 바로 배포할 공통 형식이 필요함

## Ⅱ. 특징

- 공격 그룹과 기법과 지표와 관계를 구조화해 표현할 수 있음
- 여러 보안 도구가 같은 형식으로 위협 정보를 받아 쓸 수 있음
- 배포 속도는 빨라지지만 원천 신뢰도와 유효 기간 관리는 별도로 필요함
- 표준을 도입해도 내부 탐지 규칙과 자산 맥락이 없으면 활용도가 낮음

## Ⅲ. 종류 및 비교

| 판단 기준 | STIX | TAXII |
|:---|:---|:---|
| 역할 | 위협 정보를 표현하는 표준 형식임 | 위협 정보를 교환하는 전송 방식임 |
| 다루는 대상 | 지표, 공격 기법, 관계, 캠페인 등을 담음 | 컬렉션 조회와 동기화와 배포를 담당함 |
| 활용 지점 | 내부 저장과 분석과 규칙 생성에 쓰임 | 외부 기관과 보안 도구 연동에 쓰임 |
| 유의점 | 객체 품질과 관계 정의가 중요함 | 접근 통제와 갱신 주기 관리가 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정보 생산자 | 위협 정보를 만들고 검증함 |
| STIX 객체 | 지표와 기법과 관계를 구조화해 담음 |
| TAXII 서버 | 컬렉션 단위로 정보를 배포함 |
| TAXII 클라이언트 | 필요한 정보를 받아 내부 시스템에 반영함 |
| 소비 시스템 | 관제 시스템과 단말 탐지 도구와 방화벽 같은 보안 도구가 됨 |

```text
+-------------+    STIX 생성    +-------------+    TAXII 배포    +-------------+
| 정보 생산자    | ------------> | TAXII 서버     | -------------> | 소비 시스템    |
+-------------+                +-------------+                 +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[위협 정보 수집] -> [STIX 구조화] -> [TAXII 배포] -> [내부 반영] -> [효과 점검]
```

1. **위협 정보 수집**: 외부 기관이나 내부 분석 결과를 모음
2. **STIX 구조화**: 지표와 공격 기법과 관계를 객체로 정리함
3. **TAXII 배포**: 컬렉션 형태로 소비자에게 전달함
4. **내부 반영**: 탐지 규칙과 차단 목록과 분석 시스템에 반영함
5. **효과 점검**: 실제 탐지 기여도와 오탐을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 보안 관제 조직은 외부 위협 정보를 STIX·TAXII로 받아 탐지 속도를 높일 수 있지만 출처가 불명확한 정보는 잡음만 늘리므로 신뢰 등급과 유효 기간을 함께 관리하고 실제 적중률과 오탐 증가율을 같이 확인함
2. 여러 도구에 같은 지표를 자동 배포할 때는 폐기와 갱신 절차가 꼭 있어야 하므로 지표 만료 처리와 배포 이력 관리를 함께 두고 오래된 지표 비율과 실패한 배포 건수를 계속 봐야 함

## Ⅶ. 결론

STIX와 TAXII의 핵심은 위협 정보를 많이 모으는 데 있지 않고 쓸 수 있는 형식으로 묶어 여러 방어 도구에 빠르게 흘려보내는 데 있음.
