## 미리 알고가기

- CAM은 주소를 넣으면 저장 위치를 바로 찾아주는 메모리임
- 삼진 값은 0과 1에 더해 어느 쪽이든 허용하는 값을 포함한 상태를 뜻함
- 최장 접두어 일치는 라우팅에서 더 긴 네트워크 마스크를 가진 경로를 우선하는 검색 방식임
- ACL은 패킷 허용과 차단 조건을 나열한 규칙 집합임

## Ⅰ. 개요

- **정의/개념**: TCAM은 0, 1, 무시 값을 함께 저장해 와일드카드가 들어간 규칙을 한 번에 비교할 수 있게 만든 고속 검색 메모리임
- **배경/필요성**: 라우팅과 ACL과 QoS 분류는 패킷마다 수많은 규칙을 즉시 대조해야 하므로 일반 소프트웨어 검색만으로는 선속도 처리가 어려움

## Ⅱ. 특징

- 여러 엔트리를 병렬로 비교해 매우 빠른 검색이 가능함
- 무시 값을 지원해 주소 대역이나 포트 범위 같은 규칙 표현에 유리함
- 전력 소모와 가격이 높아 용량을 무한정 늘리기 어려움
- 규칙 순서와 압축 방식에 따라 실제 활용 가능한 엔트리 수가 크게 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 메모리 기반 검색 | TCAM |
|:---|:---|:---|
| 검색 방식 | 순차 비교나 해시 계산이 필요함 | 하드웨어가 엔트리를 병렬 비교함 |
| 규칙 표현 | 정확 일치에는 유리하지만 와일드카드는 추가 로직이 필요함 | 와일드카드와 우선순위 규칙 처리에 강함 |
| 처리 속도 | 규칙 수가 늘면 지연이 증가하기 쉬움 | 대량 규칙도 짧은 시간에 찾을 수 있음 |
| 비용 특성 | 상대적으로 저렴하고 용량 확장이 쉬움 | 고가이며 전력과 발열 부담이 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 검색 키 | 목적지 주소, 포트, 프로토콜처럼 패킷에서 꺼낸 비교 대상임 |
| TCAM 엔트리 | 값과 마스크를 함께 저장해 일치 조건을 표현함 |
| 우선순위 규칙 | 여러 엔트리가 동시에 맞을 때 어떤 규칙을 적용할지 정함 |
| 액션 포인터 | 허용, 차단, 다음 홉, 큐 등 실제 동작을 가리킴 |
| 통계 카운터 | 어떤 규칙이 얼마나 자주 맞았는지 집계해 최적화에 씀 |

```text
+-----------+    +-----------+    +-----------+    +-----------+
| 패킷 헤더 추출 | -> | TCAM 병렬 비교 | -> | 우선순위 선택 | -> | 액션 적용    |
+-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 검색 키 생성   | -> | 병렬 일치 비교  | -> | 우선순위 결정   | -> | 액션 실행      | -> | 카운터 갱신    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **검색 키 생성**: 장비가 패킷 헤더에서 필요한 필드를 추출함
2. **병렬 일치 비교**: TCAM이 모든 엔트리와 동시에 비교함
3. **우선순위 결정**: 여러 엔트리가 맞으면 더 구체적이거나 우선순위가 높은 규칙을 선택함
4. **액션 실행**: 포워딩이나 필터링이나 마킹 같은 동작을 적용함
5. **카운터 갱신**: 규칙 적중 수를 기록해 운영자가 용량과 정책을 점검함

## Ⅵ. 실무 적용 및 유의점

1. 대형 라우터와 방화벽에서는 TCAM이 포워딩과 ACL 성능을 좌우하므로 규칙을 무분별하게 늘리기보다 주소 집계와 정책 정리를 먼저 하고 TCAM 사용률과 미적중 드롭을 계속 봐야 함
2. 정책 변경이 잦은 환경은 엔트리 재배치 비용과 우선순위 충돌이 장애로 이어질 수 있으므로 변경 전 시뮬레이션을 거치고 적용 뒤 검색 실패나 규칙 적중 변화가 없는지 확인해야 함

## Ⅶ. 결론

TCAM은 빠른 검색을 위해 비싼 하드웨어를 쓰는 구조이므로 성능만 볼 것이 아니라 규칙 수와 전력과 운영 복잡도까지 함께 판단해야 함
