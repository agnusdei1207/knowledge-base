# 📖 【암기용】 개념 완전 이해

> 목적: 네트워크 접근 제어(NAC)를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 네트워크에 접속하려는 사용자와 기기가 "누구인지", "안전한지"를 확인하여 허락된 사람만 들여보내는 보안 시스템
- **왜 필요한가**: 내부 직원이더라도 바이러스에 감염된 노트북을 들고 오거나, 인가되지 않은 외부인이 회사 랜선을 꽂는 것을 막아야 한다. 단순히 비밀번호만 맞는다고 다 들여보내는 게 아니라, 백신은 깔렸는지 운영체제는 최신인지까지 검사한다.
- **핵심 직관**: 건물의 출입문에 서 있는 보안 요원과 같다. 신분증(인증)도 확인하고, 위험한 물건(바이러스/취약점)은 없는지 몸수색(무결성 체크)까지 마쳐야 입장시킨다.

## 깊이 이해
- **배경·문제의식**: 예전에는 방화벽으로 외부 공격만 막으면 됐다. 하지만 이제는 내부로 들고 들어오는 개인 노트북(BYOD), 사물인터넷(IoT) 기기 등이 보안의 구멍이 되었다. "내부는 안전하다"는 믿음이 깨진 것이다.
- **작동 원리**:
  - **인증 (Authentication)**: 사용자 ID/비밀번호나 인증서로 신원을 확인한다. (802.1X 등 활용)
  - **검역/검사 (Posture Assessment)**: 접속하려는 기기의 백신 설치 여부, OS 업데이트 상태, 필수 보안 프로그램 실행 여부를 체크한다.
  - **인가/격리 (Authorization/Quarantine)**: 문제가 없으면 내부망 접근을 허용하고, 문제가 있으면 치료용 망(VLAN)으로 격리하여 백신을 먼저 설치하게 유도한다.
  - **사후 관리 (Post-admission)**: 접속 중에도 이상 행동을 하는지 계속 감시한다.
- **비유**: 공항 입국 심사대에서 비자(인증)가 있는지 확인하고, 전염병 증상(무결성)이 있으면 격리 수용소로 보내 치료 후 입국시키는 과정과 같다.
- **구체 예시**: 회사 와이파이에 연결하자마자 "보안 프로그램이 설치되지 않았습니다. 설치 페이지로 이동합니다"라는 안내가 뜨는 것이 NAC의 작동 모습이다.
- **흔한 오해·주의점**: "NAC는 방화벽과 같은 것 아닌가?"라고 할 수 있지만, 방화벽은 IP/Port 기반의 '통로'를 막는 것이고, NAC는 '기기/사용자'의 보안 상태에 따라 '접속 권한' 자체를 제어하는 것이다.

## 연결 개념
- **802.1X**: 포트 기반의 표준 인증 프로토콜 (NAC의 핵심 수단)
- **Zero Trust**: "아무도 믿지 마라"는 원칙하에 NAC를 고도화한 보안 패러다임
- **VLAN (Virtual LAN)**: 접속 등급에 따라 망을 논리적으로 분리하는 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: NAC의 3대 핵심 요소(인증, 검역, 권한제어)와 단계별 제어 흐름(Pre/Post-admission Control)을 기술적 메커니즘(802.1X, VLAN Steering, SNMP/ARP Poisoning)과 함께 체계적으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NAC는 네트워크에 접속하는 모든 단말에 대해 신원 인증과 무결성 검증을 수행하고, 보안 정책 준수 여부에 따라 접근 권한을 동적으로 제어하는 통합 보안 아키텍처이다.
> 2. **가치**: 인가되지 않은 단말의 접속 차단(Access Control)과 가시성(Visibility) 확보를 통해 내부망 보안 위협 및 컴플라이언스 리스크를 원천 차단한다.
> 3. **판단 포인트**: 환경에 따라 Agent 기반(정밀 제어) 또는 Agentless 기반(확장성) 여부와 네트워크 인프라 호환성(L2/L3 제어 방식)을 고려하여 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 내부망 보안 위협 대응 역량 확인 | 무결성 체크(Checkup), 격리(Quarantine), 정책(Policy) | 단순히 "와이파이 인증"으로만 한정하여 설명 |
| NAC 작동 메커니즘 파악 역량 | Pre-admission vs Post-admission, 802.1X, ARP/SNMP 방식 | 기술적 구현 방식(802.1X vs ARP Poisoning 등) 누락 |
| 단말 가시성 및 가용성 확보 전략 | 자산 식별(Fingerprinting), 예외 처리(Exception), 가시성 | 보안 강화만 강조하여 업무 가용성(Exception 관리) 저하 간과 |

> 요약: 인증-검역-인가-치료-사후관리로 이어지는 라이프사이클과 단말 가시성 확보 기능을 부각함.

## Ⅰ. 개요 및 필요성

- 정의: 내부 네트워크 접속 전후 단계에서 단말의 보안 상태를 점검하여 비정격 단말을 차단/격리하고 무결성을 강제하는 기술
- 배경: BYOD(Bring Your Own Device) 증가, 내부 자산 가시성 부족, 웜/랜섬웨어의 내부망 전파 위험 증대
- 필요성: 보안 정책의 자동 강제화(Compliance), 인가되지 않은 외부 기기/IoT 차단, 단말 상태 실시간 모니터링

---

## Ⅱ. 구조 및 구성요소

```text
[NAC 시스템 아키텍처]
User Device (Agent/Web) <-> Policy Server (Manager) <-> Network Device (Switch/AP)
           |                       |                           |
           +---- [802.1X/ARP] -----+----- [ACL/VLAN Change] ---+
                                   |
                         Database (AD/RADIUS/DBC)
```

| 구성요소 | 역할 및 특징 | 핵심 기술 |
|:---|:---|:---|
| 정책 서버 (Manager) | 정책 설정, 사용자 인증, 기기 무결성 판단 총괄 | RADIUS, LDAP 연동 |
| 정책 차단 (Sensor) | 단말 접속 감지 및 트래픽 차단 수행 | 802.1X, ARP Poisoning |
| 에이전트 (Agent) | 단말 내부 정보(백신, 패치) 수집 및 정책 강제 | 단말 상태 보고 (Posturing) |
| 콘솔 (Console) | 관리자용 대시보드 및 리포팅 제공 | 자산 식별 (Fingerprinting) |

> 요약: 정책 서버가 판단을 내리고 센서가 물리적으로 차단하며 에이전트가 단말 내부 상태를 검사하는 유기적 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
[NAC 제어 라이프사이클]
1. 접속 감지 -> 2. 신원 인증 -> 3. 무결성 점검 -> 4. 접근 인가 -> 5. 지속 모니터링
      |             |              |              |              |
 (L2/L3 탐지)   (ID/인증서)    (백신/패치)     (VLAN 할당)     (이상 징후)
      |             |              |              |              |
      +------------ [미준수 시] -> [격리 및 치료] <-------------------+
```

| 단계 | 처리 내용 | 기술 메커니즘 |
|:---:|:---|:---|
| 1 | 접속 감지 및 기기 식별 | SNMP Trap, DHCP Mirroring, ARP 탐지 |
| 2 | 사용자 인증 (Pre-admission) | 802.1X (EAP-TLS/PEAP), Web Portal |
| 3 | 보안 정책 점검 (Posturing) | 백신 실행 여부, 최신 패치, 금지 SW 확인 |
| 4 | 권한 부여 및 격리 | 인증 VLAN 또는 격리 VLAN 동적 할당 |
| 5 | 지속 감사 (Post-admission) | 이상 트래픽 발생 시 권한 즉시 회수 |

> 요약: 접속 단계에서 정밀 검사(Pre)를 수행하고 접속 중에도 지속적으로 감시(Post)하여 위협을 격격함.

## Ⅳ. 특징

| 구분 | Agent 기반 | Agentless 기반 | 판단 포인트 |
|:---|:---|:---|:---|
| 점검 수준 | 상세 점검 (프로세스, 레지스트리 등) | 기본 점검 (포트, 배너, HTTP 등) | 보안 강도 |
| 관리 편의성 | 설치 부담 및 호환성 문제 존재 | 설치 불필요, 관리가 용이함 | 배포 편의성 |
| 적용 단말 | PC, 노트북 (OS 기반 기기) | IoT, 프린터, IP폰 등 (임베디드) | 단말 범용성 |
| 주요 방식 | 전용 소프트웨어 설치 | SNMP, WMI, HTTP 스캐닝 | 기술적 제약 |

> 요약: 정밀한 통제가 필요한 업무용 PC는 Agent를, 설치가 불가능한 IoT 기기는 Agentless 방식을 혼용함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 802.1X 방식 | ARP Poisoning 방식 | 선택 기준 |
|:---|:---|:---|:---|
| 제어 계층 | L2 포트 기반 (스위치 연동) | L2 논리적 차단 (가짜 ARP 전송) | 인프라 지원 여부 |
| 보안 강도 | 매우 높음 (물리적 차단) | 높음 (논리적 차단) | 우회 가능성 |
| 인프라 의존성 | 스위치가 802.1X를 지원해야 함 | 스위치 기종과 무관하게 적용 가능 | 구축 난이도 |

> 요약: 인프라가 지원된다면 가장 강력한 802.1X를 권장하며, 레거시 환경에서는 ARP 방식을 선호함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 중단 (SPOF) | NAC 서버 장애 시 전체 접속 불가 | 이중화 구성 및 Fail-Open 설정 | 가동률 (Uptime) 99.9% |
| IoT 인증 불가 | SIM/ID 없는 기기의 인증 한계 | MAC 기반 화이트리스트 및 MAB 적용 | 예외 단말 등록 비율 |
| 성능 저하 | 대량 접속 시 인증 처리 병목 | 분산 센서 및 로드 밸런싱 적용 | 인증 응답 시간 < 2s |

> 요약: 시스템 가용성 확보를 위해 이중화와 예외 처리(MAB) 체계를 반드시 수립해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 자산 가시성 | 미등록 단말 탐지율 100% | NMS 연동 및 실사 비교 |
| 보안 준수율 | 백신 미설치 단말 비율 0.1% 이하 | NAC 주간 보안 리포트 |
| 격리 성공률 | 정책 미준수 단말의 망 차단 성공 여부 | 침투 테스트 및 시뮬레이션 |

> 요약: 단말 식별의 정확도와 보안 정책의 강제 집행력을 통해 NAC 운영 성과를 평가함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **BYOD 자율 보안 체계 구축**: 개인 기기 접속 시 웹 포털 인증 후 기기 무결성 확인 및 게스트 VLAN 할당으로 내부망 보호
2. **IoT 단말 프로파일링 자동화**: MAC 주소와 트래픽 패턴을 분석하여 프린터, CCTV 등을 자동 식별하고 전용 ACL(접근제어목록) 적용
3. **Zero Trust 아키텍처 연계**: NAC의 단말 신뢰도 점유 정보를 IAM(Identity Access Management)과 연동하여 세부 자원 접근 권한 결정

**결론 (2줄):**
- 기술사 판단: NAC는 단순한 인증 도구가 아니라, '단말의 상태'를 네트워크 보안의 핵심 파라미터로 끌어올린 가시성 플랫폼임
- 향후 방향: AI 기반 이상 징후 탐지(UBA)와 결합하여 사람의 개입 없이 스스로 위협을 격리하는 '자율형 NAC'로 발전할 것임
