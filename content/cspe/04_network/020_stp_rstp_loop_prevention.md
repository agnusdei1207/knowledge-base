## 미리 알고가기

- BPDU: 스위치끼리 루프 없는 트리를 계산할 때 주고받는 제어 메시지임
- Root Bridge: 스패닝 트리 계산의 기준이 되는 스위치임
- Root Port: 각 스위치가 Root Bridge로 가는 최선 경로로 선택한 포트임
- Alternate Port: RSTP에서 장애 시 즉시 대체 경로로 쓸 수 있게 대기하는 포트임

## Ⅰ. 개요

- **정의/개념**: STP 계열 프로토콜은 2계층 스위치망에서 중복 링크가 루프를 만들지 않도록 일부 포트를 논리적으로 차단해 트리 구조를 유지하는 기술임. RSTP는 이를 더 빠르게 수렴하도록 개선했고, PVST+는 VLAN별로 별도 트리를 운영하는 방식임
- **배경/필요성**: 스위치 이중화는 가용성에 필요하지만 이더넷 프레임에는 TTL이 없어 루프가 생기면 브로드캐스트 스톰과 MAC 테이블 불안정이 즉시 발생하므로 자동 차단 절차가 필요함

## Ⅱ. 특징

- STP는 중복 경로를 남겨 두되 평상시에는 일부 포트를 차단해 루프를 막음
- RSTP는 빠른 상태 전환과 대체 포트 개념으로 장애 복구 시간을 크게 줄임
- PVST+는 VLAN별 루트 브리지를 달리 가져가 링크 활용을 분산할 수 있음
- 루프 방지 자체가 목적이므로, 루트 브리지 선정과 엣지 포트 보호 정책이 잘못되면 설계 의도가 무너짐

## Ⅲ. 종류 및 비교

| 판단 기준 | STP | RSTP | PVST+ |
|:---|:---|:---|:---|
| 수렴 속도 | 타이머 중심으로 동작해 장애 복구가 느림 | 포트 역할과 핸드셰이크로 더 빠르게 수렴함 | VLAN별 별도 트리를 계산하므로 유연하지만 관리량이 늘어남 |
| 운영 단위 | 네트워크 전체에 하나의 트리를 둠 | 네트워크 전체에 하나의 트리를 두되 빠르게 계산함 | VLAN마다 개별 트리를 둠 |
| 장점 | 구조가 단순하고 기본 개념 이해에 적합함 | 실무 이중화 환경에서 가용성 확보에 유리함 | 업링크를 VLAN별로 분산해 링크 활용도를 높일 수 있음 |
| 주의점 | 차단 포트가 많고 복구가 느려 대규모 환경에 불리함 | 루트와 엣지 설정이 틀리면 빠르게 잘못 수렴할 수 있음 | VLAN 수가 많으면 제어 메시지와 관리 복잡도가 커짐 |

> 요약: 실무에서는 대체로 RSTP를 기본으로 두고, VLAN별 부하 분산이 필요하면 PVST+나 유사 기법을 함께 고려함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Root Bridge | 전체 스패닝 트리의 기준점이며, 어느 스위치를 중심으로 경로를 펼칠지 결정함 |
| Root Port | 각 비루트 스위치가 루트까지 가는 최적 경로로 선택한 포트임 |
| Designated Port | 각 세그먼트에서 프레임 전달을 맡는 활성 포트이며 세그먼트당 하나만 남음 |
| Blocking 또는 Alternate Port | 평상시에는 데이터 전달을 멈춰 루프를 막고, 장애 시 대체 경로로 전환될 수 있는 포트임 |

```text
+-------+        +--------+        +--------+
| Root  |------->|Switch B|------->|Switch C|
+-------+        +--------+        +--------+
    \                               ^
     \------------------------------/
            blocked or alternate
```

> 요약: 루프 방지는 모든 링크를 끊는 것이 아니라, 하나의 활성 경로와 하나 이상의 대기 경로를 계산해 유지하는 방식임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| BPDU교환 | --> | Root선출  | --> | Port선정  | --> | 차단유지  |
+----------+     +----------+     +----------+     +----------+
```

1. **BPDU교환**: 스위치들이 서로 BPDU를 주고받으며 현재 기준 정보를 공유함
2. **Root선출**: 가장 낮은 Bridge ID를 가진 스위치를 Root Bridge로 정함
3. **Port선정**: 각 스위치가 Root Port와 Designated Port를 계산함
4. **차단유지**: 나머지 중복 포트는 차단하거나 대기 상태로 두고, 장애가 나면 다시 수렴함

## Ⅵ. 실무 적용 및 유의점

1. 이중 업링크를 둔 캠퍼스망에서는 RSTP를 기본으로 두되 루트 브리지 우선순위를 미리 고정하지 않으면 예기치 않은 장비가 루트가 될 수 있으므로 Root Guard와 우선순위 설계를 함께 적용하고 수렴 시간과 토폴로지 변경 횟수로 확인함
2. 사용자 단말이 붙는 엣지 포트에서는 PortFast만 켜고 BPDU Guard를 빼면 임의 스위치 연결로 루프가 생길 수 있으므로 엣지 포트 보호를 함께 적용하고 BPDU 수신 차단 건수와 브로드캐스트 비율로 확인함

## Ⅶ. 결론

STP 계열 기술의 핵심은 중복 링크를 버리지 않으면서도 루프는 막는 데 있으며, 실무에서는 빠른 수렴과 루트 통제를 함께 설계해야 안정성이 나옴.
