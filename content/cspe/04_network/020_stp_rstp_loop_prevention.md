## 미리 알고가기

- BPDU: 스위치끼리 루프 없는 트리를 계산할 때 주고받는 제어 메시지임
- Root Bridge: 스패닝 트리 계산의 기준이 되는 스위치임
- Root Port: 각 스위치가 Root Bridge로 가는 최선 경로로 선택한 포트임
- Designated Port: 각 세그먼트에서 프레임 전달을 맡는 활성 포트임
- Alternate Port: RSTP에서 장애 시 대체 경로로 쓸 수 있게 대기하는 포트임

## Ⅰ. 개요

- **정의/개념**: STP 계열 프로토콜은 2계층 스위치망에서 중복 링크가 루프를 만들지 않도록 일부 포트를 논리적으로 차단해 트리 형태의 활성 경로를 유지하는 기술임
- **배경/필요성**: 스위치 이중화는 장애 대비에 필요하지만 이더넷 프레임에는 TTL이 없어 루프가 생기면 브로드캐스트 스톰과 MAC 테이블 흔들림이 발생하므로 자동 차단 절차가 필요함

## Ⅱ. 특징

- STP는 중복 경로를 남겨 두되 평상시에는 일부 포트를 차단해 루프를 막음
- RSTP는 포트 역할과 상태 전환을 개선해 장애 후 재수렴 시간을 줄임
- PVST+는 VLAN별로 별도 트리를 계산해 VLAN마다 다른 루트와 차단 포트를 둘 수 있음
- 루트 브리지와 엣지 포트 보호 정책이 틀리면 의도하지 않은 장비가 트리 기준이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | STP | RSTP | PVST+ |
|:---|:---|:---|:---|
| 수렴 방식 | 타이머 기반 상태 전환으로 동작함 | 제안과 동의 절차, 대체 포트로 더 빨리 전환함 | VLAN별 트리를 별도로 계산함 |
| 운영 단위 | 네트워크 전체에 하나의 트리를 둠 | 네트워크 전체에 하나의 트리를 두되 상태 전환을 개선함 | VLAN마다 개별 트리를 둠 |
| 적용 장점 | 기본 루프 방지 개념을 단순하게 제공함 | 이중화 링크 장애 후 복구 시간을 줄이는 데 적합함 | VLAN별 업링크 분산 설계가 가능함 |
| 주의할 점 | 차단 포트와 복구 지연을 고려해야 함 | 루트와 엣지 설정 오류가 잘못된 수렴을 유발함 | VLAN 수가 많으면 제어와 운영 확인 항목이 늘어남 |

> 요약: STP 계열은 모두 루프 없는 트리를 만들지만 수렴 방식과 VLAN별 운영 단위가 다름

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Root Bridge | 전체 스패닝 트리의 기준점이며 어느 스위치를 중심으로 경로를 펼칠지 결정함 |
| Root Port | 각 비루트 스위치가 루트까지 가는 경로로 선택한 포트임 |
| Designated Port | 각 세그먼트에서 프레임 전달을 맡는 활성 포트이며 세그먼트당 하나가 선택됨 |
| Blocking 또는 Alternate Port | 평상시에는 데이터 전달을 멈춰 루프를 막고 장애 시 대체 경로 후보가 됨 |

```text
+-------+        +--------+        +--------+
| Root  |------->|Switch B|------->|Switch C|
+-------+        +--------+        +--------+
    \                               ^
     \------------------------------/
            blocked or alternate
```

> 요약: 루프 방지는 모든 링크를 끊는 것이 아니라 하나의 활성 경로와 대기 경로를 계산해 유지하는 방식임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| BPDU교환  | --> | Root선출 | --> | Port선정  | --> | 차단유지 |
+----------+     +----------+     +----------+     +----------+
```

1. **BPDU교환**: 스위치들이 BPDU를 주고받으며 Bridge ID와 경로 비용 정보를 공유함
2. **Root선출**: 가장 낮은 Bridge ID를 가진 스위치를 Root Bridge로 정함
3. **Port선정**: 각 스위치가 Root Port와 Designated Port를 계산함
4. **차단유지**: 나머지 중복 포트는 차단하거나 대기 상태로 두고 장애가 나면 다시 수렴함

## Ⅵ. 실무 적용 및 유의점

1. 이중 업링크 캠퍼스망에서는 루트 브리지 우선순위를 미리 고정하지 않으면 예기치 않은 장비가 루트가 될 수 있으므로 Root Guard와 우선순위를 적용하고 수렴 시간과 토폴로지 변경 횟수로 확인함
2. 사용자 단말 포트에서는 PortFast만 켜고 BPDU Guard를 빼면 임의 스위치 연결로 루프가 생길 수 있으므로 엣지 포트 보호를 함께 적용하고 BPDU 차단 건수와 브로드캐스트 비율로 확인함

## Ⅶ. 결론

STP 계열 기술은 중복 링크를 유지하되 BPDU 기반 포트 선정을 통해 루프 없는 활성 경로만 남기는 절차임.

## 작성 근거(검토용)

- STP의 문맥 단어는 루트 선출, 포트 역할, 차단 상태이므로 그 절차를 중심으로 수정함
- "빠른 수렴"은 RSTP에서만 조건부로 의미가 있으므로 제안·동의, Alternate Port 같은 원인과 연결함
- 결론은 중복 링크와 루프 차단이라는 구조적 판단을 회수함
