# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 2개 이상의 스위치를 연결할 때 발생하는 **무한 루프(Loop)**를 방지하기 위해, 특정 경로를 잠시 차단해두는 프로토콜입니다.
- **필요성**: 네트워크 가용성을 위해 선을 두 개 연결(이중화)하면, 브로드캐스트 패킷이 뱅글뱅글 돌면서 망 전체를 마비시키는 **브로드캐스트 스톰(Broadcast Storm)**이 발생합니다.
- **핵심 직관**: **"순환로 차단하기"**. 동그랗게 연결된 길 중 한 곳을 막아서 나무 모양(Tree)으로 만드는 것입니다.

## 깊이 이해
- **배경 (L2 프레임의 치명적 약점)**: IP 패킷은 TTL(수명)이 있어 돌다 보면 사라지지만, 이더넷 프레임은 TTL이 없습니다. 한 번 루프에 빠지면 전원이 꺼질 때까지 무한히 복제되며 돌아다닙니다.
- **STP 작동 원리 (STA 알고리즘)**:
  1.  **Root Bridge 선출**: 네트워크의 왕(이장님)을 뽑습니다. (Bridge ID가 가장 낮은 스위치)
  2.  **Port 역할 결정**: 왕과 연결된 최단 경로(Root Port)는 살리고, 중복된 경로는 죽입니다.
  3.  **Blocking**: 루프를 만드는 포트를 논리적으로 막아버립니다. (물리적으로는 꽂혀 있음)
- **STP의 진화**:
  - **STP (802.1D)**: 원조. 장애 시 복구까지 **50초**나 걸립니다. (너무 느림)
  - **RSTP (802.1w)**: 개량형. 장애 시 **1~2초** 만에 복구합니다. (현재 표준)
  - **PVST+**: VLAN별로 각각 STP를 돌려, 노는 선 없이 골고루 트래픽을 분산합니다.
- **비유 (전기 회로)**:
  - 합선(루프)이 나지 않도록 차단기(Blocking Port)를 내려두었다가, 메인 선이 끊기면 다시 차단기를 올리는 자동 제어 시스템과 같습니다.

## 연결 개념
- **BPDU (Bridge Protocol Data Unit)**: 스위치끼리 "내가 왕이야", "여기는 내가 막을게"라고 대화할 때 쓰는 제어 메시지.
- **PortFast**: PC나 서버처럼 루프를 만들 리 없는 기기가 연결된 포트는 50초 대기 없이 즉시 통신되게 하는 설정.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: L2 이중화 구성 시 발생하는 물리적 루프를 감지하여 특정 포트를 논리적으로 차단(Blocking)함으로써 루프 프리(Loop-free) 트리 구조를 형성하는 프로토콜임.
> 2. **가치**: 브로드캐스트 스톰에 의한 네트워크 마비를 원천 차단하면서도, 장애 발생 시 차단 포트를 즉시 활성화하여 무중단 서비스 가용성을 보장함.
> 3. **판단 포인트**: 기존 STP의 느린 수렴(Convergence) 속도를 Proposal-Agreement 핸드셰이크 기반의 RSTP로 개선하여 엔터프라이즈 환경의 가용성을 확보함.

## Ⅰ. L2 루프의 원인과 STP의 정의
- **루프 발생 원인**: 가용성 확보를 위한 이중화 경로 존재 시, TTL 필드가 없는 이더넷 프레임이 무한 순환하며 브로드캐스트 스톰 유발.
- **STP (Spanning Tree Protocol)**: 스위치 간 BPDU를 교환하여 최단 경로 트리를 구성하고 중복 경로를 차단하는 IEEE 802.1D 표준 프로토콜.

## Ⅱ. STP의 동작 메커니즘 (STA: Spanning Tree Algorithm)

### 1. 3단계 선출 프로세스
1. **Root Bridge 선출**: 전체 네트워크의 기준점 선정 (가장 낮은 Bridge ID 보유 스위치).
2. **Root Port(RP) 선출**: Non-Root 스위치에서 Root로 가는 가장 빠른 포트 선정.
3. **Designated Port(DP) 선출**: 각 세그먼트(회선)에서 Root로 가는 가장 빠른 포트 선정.
   - **Blocking Port**: RP나 DP로 선택되지 못한 포트. 루프 방지를 위해 데이터 전송 차단.

### 2. 포트 상태 변화 (STP 기준)
- **Disabled** -> **Blocking** (20초) -> **Listening** (15초) -> **Learning** (15초) -> **Forwarding** (전송 가능).
- **문제점**: 장애 발생 시 통신 재개까지 최대 **50초**의 시간 소요.

## Ⅲ. 고속 수렴을 위한 RSTP (Rapid STP, 802.1w)

| 구분 | STP (802.1D) | RSTP (802.1w) |
|:---:|:---|:---|
| **수렴 속도** | 약 30~50초 (느림) | **1초 이내 (매우 빠름)** |
| **상태 변화** | 5단계 (Block, Listen, Learn, Forward, Disable) | 3단계 (Discarding, Learning, Forwarding) |
| **메커니즘** | 타이머 기반 대기 (Passive) | **Proposal-Agreement** 핸드셰이크 (Active) |
| **포트 역할** | RP, DP, Blocking | RP, DP, **Alternate(RP 백업)**, **Backup(DP 백업)** |

## Ⅳ. 주요 옵션 및 보안 기능

### 1. PortFast (Edge Port)
- PC나 서버 등 단말 장치가 연결된 포트에서 STP 계산 단계를 생략하고 즉시 Forwarding 상태로 전환.

### 2. BPDU Guard & Root Guard
- **BPDU Guard**: PortFast 포트에서 BPDU 수신 시 즉시 차단 (임의의 스위치 연결 방지).
- **Root Guard**: 의도치 않은 저사양 스위치가 왕(Root Bridge)이 되는 것을 방지.

## Ⅴ. VLAN 연동 및 부하 분산 (PVST+, MSTP)
- **PVST+ (Per-VLAN STP)**: VLAN마다 별도의 STP를 돌려 링크 가용성 극대화 (Cisco 전용).
- **MSTP (Multiple STP)**: 여러 VLAN을 하나의 인스턴스로 묶어 스위치 CPU 부하 감소 및 효율적 로드밸런싱 지원.

## Ⅵ. 기술사적 통찰: '차단'에서 '병합'으로
- **STP의 한계**: 차단 방식은 늘 절반의 대역폭을 낭비하게 됨. 이를 극복하기 위해 **Link Aggregation(LACP)**이나 **VPC/VSS** 같은 기술로 두 선을 하나로 묶어 쓰는 방식이 선호됨.
- **데이터센터의 변화**: 거대한 클라우드 데이터센터에서는 STP 대신 L3 라우팅 기반의 **Spine-Leaf** 구조나 **VXLAN**을 사용하여 루프 걱정 없는 대규모 플랫 네트워크를 구축함.
- **결론**: STP는 네트워크 이중화의 고전이자 근본이며, 최신 기술 도입 시에도 기저에서 루프를 막아주는 **"최후의 안전장치"**로서 그 중요성은 변함이 없음.
