# 📖 【암기용】 개념 완전 이해

> 목적: QKD를 처음 보는 사람도 BB84, QBER, 오류정정, 프라이버시 증폭을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 양자 상태를 이용해 송신자와 수신자가 동일한 비밀키를 생성하는 기술이다.
- **왜 필요한가**: 공격자가 키 교환 중 양자 상태를 측정하면 오류율이 증가하므로 도청 가능성을 탐지할 수 있다.
- **핵심 직관**: 남이 몰래 보면 색이 바뀌는 카드를 보내고, 바뀐 비율이 높으면 그 카드를 키로 쓰지 않는 방식이다.

## 깊이 이해
- **배경·문제의식**: RSA와 ECC는 양자컴퓨팅 발전 시 장기 기밀 보호에 불확실성이 있다. QKD는 수학 난제 대신 양자 측정 교란과 no-cloning 원리를 키 분배에 사용한다.
- **작동 원리**: BB84에서는 송신자가 서로 다른 기저로 광자를 보내고 수신자가 임의 기저로 측정한다. 이후 고전 채널에서 기저가 일치한 비트만 남기고, QBER를 계산한 뒤 오류정정과 프라이버시 증폭으로 최종 키를 만든다.
- **비유**: 서로 다른 두 종류의 자물쇠로 편지를 보내고, 받는 사람이 맞는 자물쇠로 연 편지만 골라 암호책을 만드는 과정과 같다.
- **구체 예시**: 두 데이터센터 사이 50km 광섬유 QKD 링크에서 QBER가 임계값 이하이면 키 관리자가 IPsec 장비에 주기적으로 세션 키를 공급한다.
- **흔한 오해·주의점**: QKD는 데이터를 직접 암호화하는 기술이 아니다. 키를 분배하고, 실제 데이터 암호화는 AES, IPsec, MACsec 같은 기존 장비가 수행한다.

## 연결 개념
- BB84 — 대표적인 prepare-and-measure QKD 프로토콜
- QBER — 도청·잡음 가능성을 판단하는 양자 비트 오류율
- Privacy Amplification — 공격자가 알 수 있는 정보를 줄여 최종 키를 만드는 절차

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. BB84, QBER, error correction, privacy amplification, key manager를 중심으로 작성한다.
> 핵심: 출제자는 QKD의 도청 탐지 원리와 실제 암호 시스템 연동 한계를 함께 확인한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: QKD는 양자 상태 송수신과 고전 채널 후처리를 통해 송수신자가 동일한 비밀키를 생성하는 키 분배 기술이다.
> 2. **가치**: 도청 시 양자 상태 측정 교란이 QBER 증가로 나타나므로 키 폐기 여부를 판단할 수 있다.
> 3. **판단 포인트**: QKD는 인증 채널, 키 관리자, 암호 장비 연동, 거리·광손실 조건이 충족되어야 운영 가능하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| QKD 원리 이해 확인 | BB84, 기저 비교, QBER, privacy amplification | QKD를 양자 암호화 데이터 전송으로 설명 |
| 도청 탐지 판단 확인 | 측정 교란, 오류율 임계값, 키 폐기 | 도청을 100% 차단한다고 단정 |
| 실무 연동 한계 확인 | key manager, IPsec/MACsec 연동, 인증 채널 | QKD만으로 인증·암호화 전 과정을 대체한다고 서술 |

> 요약: 이 문제는 BB84 절차와 QBER 기반 키 폐기 판단, 기존 암호 장비 연동을 연결해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 양자 상태로 비밀키를 분배함.
- 배경: 장기 기밀 데이터는 향후 양자컴퓨팅 발전에 따른 공개키 교환 위험을 고려해야 함.
- 필요성: QKD는 전용 구간에서 키 교환 도청 가능성을 QBER로 탐지하고 키 폐기 여부를 판단함.
- 판단 기준: QBER, key rate, link distance, authentication, key manager 연동 여부를 확인함.

---

## Ⅱ. 구조 및 구성요소

```text
Alice Photon Source -> Quantum Channel -> Bob Detector
Alice Control -> Classical Auth Channel -> Bob Control
Sifted Key -> Error Correction -> Privacy Amplification -> Key Manager
Key Manager -> IPsec / MACsec / OTN Encryptor
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 광자 송신기 | 비트와 기저를 선택해 양자 상태 전송 | BB84, decoy-state 적용 가능 |
| 광자 검출기 | 수신 기저로 광자 측정 | 검출 효율, detector noise 영향 |
| 고전 인증 채널 | 기저 비교와 후처리 정보 교환 | 메시지 인증 필수 |
| 후처리 모듈 | 오류정정과 프라이버시 증폭 수행 | QBER 기준으로 키 폐기 |
| 키 관리자 | 최종 키를 암호 장비에 제공 | ETSI QKD API 검토 |

> 요약: QKD는 양자 채널에서 키 재료를 만들고 고전 인증 채널 후처리로 최종 키를 확정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
랜덤 비트·기저 선택 -> 광자 전송 -> 수신 기저 측정
-> 기저 공개·불일치 비트 제거 -> QBER 계산 -> 오류정정 -> 프라이버시 증폭 -> 키 공급
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Alice가 랜덤 비트와 기저로 광자를 생성 | 난수 품질, 송신률 |
| 2 | Bob이 임의 기저로 광자를 측정 | 검출률, dark count |
| 3 | 고전 채널에서 기저 일치 비트를 선별 | 인증, replay 방지 |
| 4 | QBER가 임계값을 넘으면 키 폐기 | QBER, sample size |
| 5 | 오류정정과 프라이버시 증폭 후 키 공급 | final key rate |

> 요약: QKD는 기저 일치 비트만 남기고 QBER로 도청 가능성을 판단한 뒤 후처리로 최종 키를 생성한다.

## Ⅳ. 특징

| 구분 | 공개키 키교환 | QKD | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 보안 근거 | RSA·ECC 난제 | 양자 측정 교란 | QBER, no-cloning |
| 전송 채널 | 인터넷 가능 | 양자 채널 + 고전 채널 | 광섬유·자유공간 |
| 적용 범위 | 범용 TLS·IPsec | 전용 링크 중심 | key rate, km, loss |
| 한계 | 양자 공격 대비 필요 | 장비·거리·인증 제약 | ETSI QKD, key manager |

> 요약: QKD는 키 분배의 도청 탐지를 제공하지만, 데이터 암호화와 인증은 기존 암호 체계와 결합해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | QKD | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | TLS, IKE, PKI | QKD 장비 + key manager + 암호 장비 | 전용 광링크와 고가치 데이터 구간 |
| 비용/성능 | 소프트웨어 중심 | 전용 장비와 링크 예산 필요 | key rate가 세션 키 요구량 충족 시 |
| 운영/위험 | 인증서 관리 중심 | QBER, 검출기, 물리보안 관리 | 노드 접근통제와 유지보수 가능 시 |

> 요약: QKD는 모든 인터넷 서비스보다 제한된 전용 구간의 키 분배 보완 수단으로 판단해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| QBER 증가 | 광손실, 장비 잡음, 도청 가능성 | 링크 점검, 키 폐기, 경보 처리 | QBER 추이 |
| 키 부족 | 거리 증가와 검출률 저하 | 링크 예산 재설계, 키 캐시 | final key rate |
| 인증 취약 | 고전 채널 메시지 위조 | 사전 공유키 또는 PQC 인증 | 인증 실패 로그 |

> 요약: QKD 운영은 QBER, key rate, 인증 실패를 주요 위험 지표로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 도청 탐지 | QBER 임계값 초과 시 키 폐기 | QKD 장비 통계 |
| 키 공급 | key manager 장애 0건 | 키 제공 API 로그 |
| 연동 검증 | IPsec/MACsec 키 교체 성공률 99% 이상 | 암호 장비 이벤트 |

> 요약: QKD 성과는 QBER 제어, 키 공급 연속성, 암호 장비 키 교체 성공률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 데이터센터 간 전용 광링크에 BB84 또는 decoy-state QKD PoC를 구성하고 QBER, final key rate, 장애 복구 시간을 측정함.
2. key manager는 IPsec, MACsec, OTN 암호 장비와 연동하고 키 부족 시 기존 IKE 또는 PQC 기반 키 교환으로 전환함.
3. 고전 채널 인증, 장비 물리보안, 운영자 접근통제, 감사로그를 QKD 운영 절차에 포함함.

**결론 (2줄):**
- 기술사 판단: QKD는 전용망 키 분배 보완에는 유효하나 범용 인터넷은 PQC 전환과 하이브리드 키 교환을 병행해야 함.
- 향후 방향: ETSI QKD 인터페이스, key management 표준화, PQC 하이브리드 구조가 함께 확산됨.
