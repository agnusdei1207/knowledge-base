## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 패킷이 목적지에 도달하지 못하고 라우터 사이를 무한히 순환하는 네트워크 장애를 막는 기술 |
| **배경/필요성** | 거리 벡터 방식에서 토폴로지 변경 사항 동기화 지연으로 발생하는 대역폭 고갈 및 마비 방지 필요 |
| **출제 의도** | Split Horizon, Poison Reverse 등 벡터 라우팅 고유의 루프 차단 메커니즘 동작 원리 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+
| Router A | ----> | Router B |
| (Update) | <---- | (Loop)   |
+----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Split Horizon | 어떤 포트로 수신한 라우팅 정보를 다시 그 포트로는 보내지 않는 규칙 | 메아리 방지기 |
| Poison Reverse | 수신한 포트로 되돌려 보낼 때 경로 비용을 무한대(16)로 설정하여 차단 | 접근 금지선 |
| Hold-Down | 경로 장애 발생 시 일정 시간 다른 라우터의 갱신 정보를 무시하는 타이머 | 관망 타이머 |

> 요약: 수신 경로 재전송 차단과 무한대 메트릭 적용으로 잘못된 경로 정보 확산을 억제함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 장애 발생| -> | 즉시 통보| -> | 스플릿 H.| -> | TTL 폐기 |
+----------+    +----------+    +----------+    +----------+
```
1. 장애 발생: 라우터가 직접 연결된 링크의 단절(Down) 상태 즉각 인지
2. 즉시 통보: Triggered Update를 통해 대기 시간 없이 즉시 도달 불가(Poison) 정보 전파
3. 스플릿 H.: 인접 라우터는 해당 정보를 수신한 인터페이스로는 기존 경로를 재광고하지 않음
4. TTL 폐기: 그럼에도 발생한 순간적 루프 패킷은 IP 헤더의 TTL 감소에 의해 최종 폐기됨

> 요약: 정보 차단(Split Horizon)과 오염 통보(Poison Reverse)를 결합하여 라우팅 안정성을 지킴

## Ⅳ. 문제점
- Hold-Down 타이머 설정 시 정상적 우회 경로 정보까지 차단되어 네트워크 수렴 지연 원인
- 복잡한 토폴로지에서 라우터 간 갱신 주기가 엇갈리면 순간적인 마이크로 루프 필연적 발생
- RIP 등에서 최대 홉수를 15로 제한하여 대규모 엔터프라이즈 망에는 적용 불가능

## Ⅴ. 개선방안
- [단기] 장애 감지 시 Triggered Update 활성화로 정기 갱신 대기 없이 신속히 상태 전파
- [중기] BFD(Bidirectional Forwarding Detection) 연동을 통한 밀리초 단위 물리 링크 장애 감지
- [장기] 근본적 루프 프리(Loop-Free) 특성을 지닌 링크 상태 프로토콜(OSPF/IS-IS)로 망 구조 개편

## Ⅵ. 전망
- 트래픽 경로를 송신자가 명시하는 SR(Segment Routing) 기반 환경으로 진화해 중간 루프가 사라질 전망임
