# 📖 【암기용】 개념 완전 이해

> 목적: 소스 코딩을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 원천 데이터의 중복을 제거해 평균 비트 수를 줄이는 압축 부호화 기술
- **왜 필요한가**: 텍스트, 이미지, 음성, 로그는 반복 패턴과 확률 편차가 있다. 자주 나오는 심벌에 짧은 코드, 드문 심벌에 긴 코드를 부여하면 저장공간과 전송량을 줄일 수 있다.
- **핵심 직관**: 자주 쓰는 단어는 약어로, 드문 단어는 긴 표기로 적어 전체 문서 길이를 줄이는 방식이다.

## 깊이 이해
- **배경·문제의식**: 정보원은 심벌별 발생 확률이 다르다. 고정 길이 부호는 확률 차이를 활용하지 못한다. 소스 코딩은 엔트로피 H(X)를 이론 하한으로 삼아 평균 부호 길이를 줄인다.
- **작동 원리**: 허프만 코딩은 심벌 확률을 기반으로 prefix-free 이진 트리를 만든다. 산술 코딩은 메시지 전체를 0과 1 사이 구간으로 표현해 허프만보다 엔트로피에 더 근접할 수 있다.
- **비유**: 지하철 안내에서 매일 반복되는 역 이름은 번호로 줄이고, 드문 안내 문구는 길게 유지하는 방식과 같다.
- **구체 예시**: 심벌 A 50%, B 25%, C 15%, D 10%이면 A에 `0`, B에 `10`, C/D에 더 긴 코드를 배치해 평균 비트 수를 고정 2비트보다 낮춘다.
- **흔한 오해·주의점**: 소스 코딩은 채널 오류를 정정하지 않는다. 압축된 비트열은 1비트 오류에도 복원 실패가 커질 수 있어 채널 코딩과 함께 설계한다.

## 연결 개념
- 엔트로피 — 평균 정보량과 무손실 압축 한계
- 채널 코딩 — 오류 정정을 위해 중복을 추가하는 기술
- JPEG/PNG/ZIP — 소스 코딩을 실제 파일 압축에 적용한 예

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 소스 코딩은 엔트로피 한계, 평균 부호 길이, prefix-free 조건, 허프만·산술 비교가 답안 중심이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소스 코딩은 정보원 심벌 확률을 이용해 평균 부호 길이를 엔트로피 H(X)에 가깝게 줄이는 압축 기술이다.
> 2. **가치**: 저장공간과 전송 비트 수를 줄이며, 허프만은 prefix-free 트리, 산술 코딩은 구간 분할로 고압축률을 달성한다.
> 3. **판단 포인트**: 무손실/손실, 정적/동적 모델, 평균 길이 L, 엔트로피 H(X), 복잡도와 오류 민감도를 비교해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 압축 원리 이해 확인 | 엔트로피, 평균 부호 길이, prefix-free | 채널 코딩과 혼동 |
| 알고리즘 비교 판단 | Huffman tree, arithmetic interval | 단순 장단점 나열 |
| 적용 조건 인식 | 심벌 확률 모델, 무손실 압축, 오류 민감도 | 압축률 수치·한계 누락 |

> 요약: 이 문제는 중복 제거 원리와 허프만·산술 코딩의 확률 모델 기반 차이를 묻는다.

## Ⅰ. 개요 및 필요성

소스 코딩은 원천 정보의 중복을 제거하는 압축 부호화이다. 데이터는 심벌 발생 확률이 균등하지 않아 고정 길이 부호가 비트 낭비를 만든다. 엔트로피 H(X)를 기준으로 평균 부호 길이를 줄여 저장·전송 비트 수를 감소시킨다.

---

## Ⅱ. 구조 및 구성요소

```text
Source Data -> Symbol Modeling -> Probability Estimation
-> Encoder Huffman/Arithmetic -> Compressed Bitstream
-> Decoder -> Recovered Data
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Source Model | 심벌과 발생 확률 추정 | static/adaptive model |
| Huffman Encoder | prefix-free 가변 길이 코드 생성 | 정수 bit length 제약 |
| Arithmetic Encoder | 전체 메시지를 확률 구간으로 표현 | 엔트로피 근접, 구현 복잡도 |
| Decoder | 코드 테이블 또는 확률 모델로 복원 | 모델 동기화 필요 |

> 요약: 소스 코딩은 심벌 확률 모델을 만들고 허프만 또는 산술 방식으로 짧은 비트열을 생성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Input Symbols -> Count Frequency -> Build Probability Model
-> Assign Variable Code or Interval -> Emit Bitstream
-> Decode with Same Model -> Verify Lossless Recovery
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 심벌 빈도와 확률 계산 | probability sum 1.0 |
| 2 | 엔트로피 H(X) 산출 | H(X) = -sum p log2 p |
| 3 | 허프만 트리 또는 산술 구간 생성 | prefix-free 또는 interval consistency |
| 4 | 압축 비트열 생성과 복원 | 원본 hash 일치 |
| 5 | 압축률과 평균 길이 측정 | L >= H(X), compression ratio |

> 요약: 소스 코딩은 확률 모델을 기준으로 부호를 만들고, 평균 길이 L이 엔트로피에 얼마나 근접하는지로 평가한다.

---

## Ⅳ. 특징

| 구분 | 허프만 코딩 | 산술 코딩 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 방식 | prefix-free 이진 트리 | 0~1 구간 세분화 | L과 H(X) 차이 |
| 압축 한계 | 정수 비트 길이 제약 | 엔트로피 근접 | fractional bit 표현 가능 |
| 복잡도 | 구현 단순 | 곱셈·구간 정밀도 필요 | CPU, 메모리, 지연 |
| 적용 | PNG, ZIP 일부 | JPEG2000, 영상 부호화 | 특허·구현 이력 고려 |

> 요약: 허프만은 구현과 복호가 단순하고, 산술은 확률 모델이 정확할수록 엔트로피에 더 근접한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 부호 길이 | 고정 길이 | 가변 길이 소스 코딩 | 심벌 확률 편차 존재 |
| 알고리즘 | 허프만 | 산술 코딩 | 압축률 우선, 복잡도 허용 |
| 운영/위험 | 비압축 전송 | 압축 후 전송 | CPU 예산과 오류 민감도 |

> 요약: 심벌 확률이 치우칠수록 소스 코딩 효과가 크며, 압축률과 계산량 사이에서 방식을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 모델 불일치 | 인코더·디코더 확률 모델 차이 | header에 table 저장, adaptive sync | decode failure 0건 |
| 오류 전파 | 압축 비트열 1비트 훼손 | CRC, chunking, channel coding | corrupted block rate |
| 계산량 증가 | 산술 코딩 정밀도 연산 | SIMD, hardware codec, block size 조정 | encode throughput MB/s |

> 요약: 압축률만이 아니라 모델 동기화, 오류 전파, 처리량을 함께 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 압축률 | 원본 대비 30%~70% 수준 목표 | file size ratio |
| 평균 길이 | L/H(X) 1.0~1.1 | entropy analysis |
| 처리량 | 서비스 요구 MB/s 이상 | benchmark, profiler |

> 요약: 소스 코딩 성과는 압축률, 엔트로피 근접도, 처리량을 함께 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 로그·텍스트는 심벌 빈도 분석 후 허프만 또는 LZ+허프만 조합을 적용하고 압축률과 CPU 사용률을 측정함
2. 영상·이미지처럼 확률 모델이 세밀한 영역은 산술 코딩 또는 CABAC 계열을 검토하고 지연 예산을 ms 단위로 제한함
3. 압축 블록마다 CRC와 길이 헤더를 넣고, 무선·저장 경로에서는 채널 코딩과 결합해 오류 전파를 차단함

**결론 (2줄):**
- 기술사 판단: 심벌 확률 편차가 크고 무손실 복원이 필요하면 소스 코딩을 적용하되 CPU·지연 예산을 함께 검토함
- 향후 방향: 데이터 특성별 adaptive model과 하드웨어 codec을 결합해 압축률과 처리량을 동시에 관리함
