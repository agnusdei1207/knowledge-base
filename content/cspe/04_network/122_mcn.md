## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 복수의 퍼블릭 클라우드와 온프레미스 환경을 일관된 정책으로 연결하는 아키텍처임 |
| 배경 | 클라우드 분산화로 인한 이기종 환경 통합 및 관리 복잡성 증가 해결 필요 |
| 출제 | 클라우드 통합 관리, SD-WAN 확장, 가시성 및 보안 정책 일원화 |

## Ⅱ. 구성요소
```text
+-------------+      +-------------+      +-------------+
| Management  |      |   Control   |      |    Data     |
|   Plane     | ---> |    Plane    | ---> |    Plane    |
+-------------+      +-------------+      +-------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 관리 평면 | 멀티 클라우드 네트워크의 가시성 및 통합 설정 관리 제공함 | 종합 관제실 |
| 제어 평면 | 각 CSP별 API를 연동하여 라우팅 및 보안 정책 배포함 | 신호등 제어기 |
| 데이터 평면 | 가상 게이트웨이를 통해 이기종 클라우드 간 트래픽 전송함 | 도로망 |

> 요약: 관리, 제어, 데이터 평면 분리를 통해 이기종 클라우드를 통합 관리함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Deploy | -> | 2. Connect| -> | 3. Policy | -> | 4. Monitor|
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 게이트웨이 배포 (Deploy): 각 클라우드 환경에 MCN 가상 게이트웨이 생성함.
2. 네트워크 연결 (Connect): VPC/VNet 간 글로벌 트랜짓 네트워크 구성함.
3. 정책 적용 (Policy): 제어 평면에서 중앙 집중형 보안 및 라우팅 정책 하달함.
4. 모니터링 (Monitor): 전체 경로의 트래픽을 단일 대시보드에서 가시화함.

> 요약: 게이트웨이 생성 및 연동 후 중앙 정책을 배포하고 모니터링함.

## Ⅳ. 문제점
- API 종속성: 각 CSP 고유 네트워크 아키텍처와 API 제어 차이 존재함.
- 지연시간: 여러 클라우드 벤더를 경유 시 라우팅 오버헤드 증가함.
- 라이선스: MCN 서드파티 솔루션 도입 시 추가적인 운영 비용 발생함.

## Ⅴ. 개선방안
- 추상화 적용 (단기): 테라폼 등 IaC 기반의 공통 프로비저닝 인터페이스 활용함.
- 최적 라우팅 (중기): 글로벌 백본망 기반 지능형 경로 탐색(IBN) 연계함.
- 오픈소스 표준화 (장기): ONAP 등 오픈소스 생태계 통합으로 비용 및 종속성 완화함.

## Ⅵ. 전망
- MCN은 클라우드 네이티브 환경의 K8s CNI와 통합되어 컨테이너 레벨의 제어까지 제공할 것임.
