## 미리 알고가기

- 패킷 캡처는 네트워크를 지나가는 통신 내용을 그대로 저장하는 방식임
- 플로우 기록은 누가 누구와 얼마나 통신했는지 요약한 메타데이터임
- 탭 장비와 미러링 포트는 네트워크 트래픽을 복사해 수집 장비로 보내는 관측 수단임
- 증거 보전은 수집한 데이터를 변경되지 않게 관리하는 절차임
- 해시는 파일이나 증거가 변하지 않았는지 확인하는 값임

## Ⅰ. 개요

- **정의/개념**: 네트워크 포렌식은 패킷과 플로우와 장비 로그를 수집해 침해 경로와 행위 순서를 재구성하고 증거로 보전하는 조사 절차임
- **배경/필요성**: 공격자는 흔적을 지우거나 여러 시스템을 거쳐 움직이기 쉬우므로, 개별 서버 로그만으로는 부족한 경우가 많아 네트워크 관점의 시간 흐름 복원이 필요함

## Ⅱ. 특징

- 여러 시스템을 가로지르는 통신 흐름을 한 번에 추적할 수 있음
- 호스트가 지워져도 네트워크 기록이 남아 있으면 사건 재구성에 도움이 됨
- 전체 패킷은 세션 내용을 재구성할 수 있지만 페이로드 저장량과 개인정보 노출 범위가 증가함
- 시간 동기화와 증거 무결성이 흔들리면 조사 결과 신뢰가 떨어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 전체 패킷 수집 | 플로우·로그 중심 수집 |
|:---|:---|:---|
| 수집 정보 | 통신 내용과 세부 필드까지 확보함 | 통신 요약과 장비 이벤트 중심임 |
| 분석 범위 | 페이로드와 세션 내용을 재구성함 | 주소·포트·바이트·시간 흐름을 분석함 |
| 저장량 | 패킷 헤더와 페이로드를 저장함 | 흐름별 요약 레코드를 저장함 |
| 적용 환경 | 고위험 구간의 세션 내용 조사 | 광범위한 구간의 장기 흐름 분석 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 수집 지점 | 탭 장비와 미러링 포트와 방화벽과 라우터 같은 관측 지점임 |
| 패킷·플로우 저장소 | 원본 트래픽과 요약 정보를 보관함 |
| 로그 원천 | 보안 장비와 서버 로그를 함께 모음 |
| 분석 도구 | 시간대와 세션과 공격 흔적을 재구성함 |
| 증거 관리 체계 | 해시와 접근 통제로 무결성을 보전함 |

```text
+----------+    수집    +--------------+    분석    +-------------+
| 네트워크 지점 | ------> | 증거 저장소     | ------> | 포렌식 분석     |
+----------+          +--------------+          +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[범위 설정] -> [증거 수집] -> [무결성 보전] -> [행위 재구성] -> [보고]
```

1. **범위 설정**: 사고 구간과 기간과 관련 자산을 정함
2. **증거 수집**: 패킷과 플로우와 로그를 확보함
3. **무결성 보전**: 해시와 접근 통제로 원본을 보전함
4. **행위 재구성**: 통신 순서와 침해 경로를 분석함
5. **보고**: 증거와 결론과 한계를 정리함

## Ⅵ. 실무 적용 및 유의점

1. 인터넷 경계나 데이터센터 핵심 구간은 네트워크 포렌식 가치가 크지만 수집 위치가 어긋나면 중요한 흐름을 놓치므로 탭 장비 배치와 시간 동기화를 함께 점검하고 패킷 손실률과 타임스탬프 오차와 증거 수집 누락 건수를 같이 확인함
2. 전체 패킷 저장은 조사에 유리하지만 개인정보와 저장 비용 부담이 크므로 보존 기간과 마스킹 정책을 함께 정하고 저장 용량 증가율과 증거 접근 이력을 지속적으로 봐야 함

## Ⅶ. 결론

네트워크 포렌식의 핵심은 많이 저장하는 데 있지 않고 필요한 구간의 통신 흐름을 무결하게 남겨 사건을 시간 순서대로 다시 세우는 데 있음.
