## Ⅰ. 개요
- **정의**: 네트워크를 가변 길이 프리픽스로 분할·집약하는 IP 주소 할당 기법
- **배경/필요성**: 클래스 기반 할당(006 참조)의 주소 낭비를 해소하고 라우팅 테이블을 축소할 필요가 있음
- **비유**: 큰 토지를 용도별로 가변 크기 필지로 분할·합필하는 것과 동일함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 서브넷 계산과 CIDR 표기 이해 | /prefix 표기, 서브넷·호스트 수 계산 | 네트워크·브로드캐스트 주소 누락 |

> 요약: 프리픽스 길이 기반 가변 분할로 주소 효율성과 라우팅 집약을 동시에 달성함

## Ⅱ. 구성요소
```text
CIDR: 192.168.1.0/26
      |<-26bit Net->|<-6bit Host->|
      Network Addr   Host Addr

Subnetting /24 --> /26 (4 subnets)
  192.168.1.0/26   (0~63)
  192.168.1.64/26  (64~127)
  192.168.1.128/26 (128~191)
  192.168.1.192/26 (192~255)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Prefix Length | 네트워크부 비트 수, /n 표기(예: /24) | 필지 경계선 위치 |
| Subnet Mask | 프리픽스를 10진수로 표현(예: 255.255.255.0) | 구역 경계 울타리 |
| Network Address | 호스트부가 모두 0인 서브넷 식별 주소 | 아파트 단지 이름 |
| Broadcast Address | 호스트부가 모두 1인 브로드캐스트용 주소 | 단지 전체 방송 |
| Supernetting | 복수 네트워크를 상위 프리픽스로 집약(경로 축약) | 소필지를 대필지로 합필 |

> 요약: 프리픽스 길이로 분할(서브네팅)과 집약(슈퍼네팅)을 유연하게 수행함

## Ⅲ. 절차
```text
[호스트 수 산정] --> [프리픽스 결정] --> [서브넷 분할] --> [라우팅 집약]
```
- 1단계: 각 세그먼트별 필요 호스트 수를 파악하여 호스트부 비트 수 결정
- 2단계: 2^(호스트비트) - 2 >= 필요 호스트 수를 만족하는 프리픽스 길이(/n) 산출
- 3단계: 결정된 프리픽스로 주소 블록을 서브넷 단위로 분할하여 각 세그먼트에 배정
- 4단계: 인접 서브넷을 상위 프리픽스로 집약(슈퍼네팅)하여 라우팅 테이블 축소

> 요약: 호스트 산정→프리픽스 결정→분할→집약의 순서로 주소를 체계적으로 설계함

## Ⅳ. 문제점
- 설계 복잡성: 가변 프리픽스 계산 시 비트 연산 오류 발생 빈도 높음 — 수작업 설계의 한계
- 집약 불가 사례: 비연속 주소 블록 할당 시 슈퍼네팅 불가 — 라우팅 테이블 축소 효과 감소
- IPv4 한계 지속: CIDR로 낭비를 줄여도 32비트 주소 공간 자체의 절대 부족은 미해결

> 요약: 설계 복잡성, 비연속 블록 집약 불가, IPv4 공간 한계가 잔존함

## Ⅴ. 개선방안
1. 단기: IP 주소 관리 도구(IPAM) 도입으로 서브넷 설계·할당 자동화
2. 중기: 주소 할당 정책 체계화로 연속 블록 확보 및 슈퍼네팅 가능성 확대
3. 장기: IPv6(008 참조)의 128비트 주소 전환으로 근본적 공간 부족 해소

> 요약: IPAM 자동화, 할당 정책 체계화, IPv6 전환으로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: 클라우드 VPC 설계에서 CIDR 기반 자동 서브넷 할당이 표준화 중
- 기술사적 판단: CIDR 계산 능력은 네트워크 설계 실무의 기초 역량임
- 기술사 제언: 멀티 클라우드 환경에서 IP 대역 충돌 방지를 위한 CIDR 설계 역량이 핵심임
