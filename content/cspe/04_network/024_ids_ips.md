# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: IDS(Intrusion Detection System)·IPS(Intrusion Prevention System)는 네트워크 트래픽이나 호스트 로그를 **시그니처·행위 기반**으로 분석하여 **침입을 탐지(IDS)하거나 실시간 차단(IPS)**하는 보안 시스템임.
- **왜 필요한가**: 방화벽(023)은 허용된 포트(80·443)로 들어오는 트래픽은 통과시키므로, 정상 포트를 통한 L7 공격(SQLi·버퍼 오버플로우)을 잡아내는 2차 방어선이 필수임.
- **핵심 직관**: IDS는 도둑이 담을 넘을 때 "도둑이야!" 경보만 울리는 CCTV이고, IPS는 도둑이 넘자마자 전기 충격으로 막는 스마트 철조망. 단, 스마트 철조망이 고양이(정상)를 도둑으로 오인하면(오탐) 집주인도 못 들어옴.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 침입 탐지·차단 (상위 키워드) | 비인가 접근·악성 행위를 식별하여 경보 또는 차단하는 보안 메커니즘 | 도둑 감지 경보기 vs 전기 철조망 |
| Out-of-band (IDS) | 트래픽 복사본(SPAN/TAP)을 분석하는 구성 — 원본 트래픽 경로에 영향 없음 | 통화 녹음을 나중에 듣는 것 |
| In-line (IPS) | 트래픽 경로 중간에 장비를 삽입하여 직접 패킷을 Drop하는 구성 | 검문소에서 직접 차단 |
| 오용 탐지 (Signature-based) | 알려진 공격 패턴(시그니처) DB와 패킷을 대조 — 오탐 낮으나 제로데이 미탐 | 지명수배자 몽타주 대조 |
| 이상 탐지 (Anomaly-based) | 정상 트래픽 베이스라인을 학습 후 이탈을 탐지 — 제로데이 가능하나 오탐 높음 | 여름에 패딩 입은 사람 의심 |
| False Positive (과탐, FP) | 정상 트래픽을 공격으로 오인 — IPS에서 가장 치명적(서비스 중단) | 고양이를 도둑으로 오인 |
| False Negative (미탐, FN) | 실제 공격을 정상으로 통과시킴 | 진짜 도둑을 못 잡음 |
| Hardware Bypass (Fail-open) | IPS 장비 장애 시 트래픽이 차단되지 않고 우회하는 안전장치 | 검문소 고장 시 개방 |
| NIDS/HIDS | 네트워크 기반(NIDS)은 세그먼트 전체 감시, 호스트 기반(HIDS)은 서버 개별 감시 | 도로 CCTV vs 집 안 CCTV |

## 깊이 이해
- **배경·문제의식**: 방화벽(023)은 포트 기반 통제이므로 허용 포트를 통한 L7 공격은 막지 못함. 초기 IDS는 트래픽 복사본(Out-of-band)을 분석하여 경보만 발생시켜, 경보 시점에 이미 공격 패킷이 서버에 도달한 뒤였음(사후 대응 한계). 이를 극복하기 위해 트래픽 경로 중간(In-line)에서 직접 패킷을 Drop하는 IPS가 등장함.
- **오용 탐지 작동 원리**: 수신 패킷을 정규화(IP 단편화 조립·프로토콜 디코딩) 후, 시그니처 DB(Snort·Suricata 룰셋)와 패턴 매칭함. `UNION SELECT` 같은 알려진 SQLi 패턴을 빠르게 탐지하나, DB에 없는 신종 공격(제로데이)은 놓침.
- **이상 탐지 작동 원리**: 정상 트래픽의 베이스라인(프로토콜 비율·세션 수·데이터량)을 ML로 학습 후, 갑작스러운 이탈(예: 새벽 3시 대량 SSH 시도)을 탐지함. 제로데이·변종을 잡을 수 있으나, 정상 트래픽 급증(이벤트·세일)을 공격으로 오인하는 높은 FP율이 단점임.
- **IDS vs IPS 핵심 차이**: IDS는 Out-of-band(SPAN/TAP으로 복사본 분석)이므로 서비스 가용성에 영향 없으나 사후 대응만 가능함. IPS는 In-line(트래픽 경로 중간)이므로 실시간 차단이 가능하나, 장비 장애 시 SPOF가 되고 오탐 시 정상 서비스를 차단함.
- **비유**: 오용 탐지는 몽타주(시그니처)와 얼굴을 대조하는 것이라 빠르고 정확하나 처음 보는 범인은 놓치고, 이상 탐지는 "수상한 행동"을 감시하는 것이라 새로운 범인도 잡지만 합법적 행인도 잡아감.
- **구체 예시**: 서버로 향하는 패킷에 `' OR 1=1 --` 문자열이 포함되면, IDS는 관리자에게 경보 이메일을 보내고 패킷은 서버에 도달하지만, IPS는 해당 패킷을 즉시 Drop하고 TCP RST를 전송하여 세션을 강제 종료함.
- **흔한 오해·주의점**: "차단이 탐지보다 무조건 좋으니 IPS만 쓰면 된다"는 틀림. IPS의 오탐(FP)은 곧 서비스 중단이므로, 보통 초기에는 IPS를 탐지 모드(IDS 모드)로 운영하며 시그니처를 튜닝한 뒤 차단 모드로 전환함. 또한 IPS In-line 장비 장애 시 SPOF가 되므로 Hardware Bypass(Fail-open)가 필수임.

## 연결 개념
- **방화벽(023)**: IDS/IPS는 방화벽의 허용 포트를 통과하는 공격을 탐지·차단하는 2차 방어선.
- **NGFW(023)**: NGFW에 IPS 기능이 통합되어 독립 IPS 장비가 축소되는 추세.
- **SIEM·SOAR(118·119)**: IDS/IPS 경보를 수집·분석·자동 대응하는 보안 관제 시스템.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IDS는 Out-of-band에서 경보, IPS는 In-line에서 실시간 차단하는 침입 탐지·방지 시스템이며, 오용·이상 탐지 두 기법을 병행함.
> 2. **가치**: 방화벽이 막지 못하는 L7 공격(SQLi·버퍼 오버플로우)을 시그니처·행위 분석으로 식별하여 2차 방어선을 구축함.
> 3. **판단 포인트**: IPS In-line 구성의 가용성 리스크(SPOF·오탐)를 Hardware Bypass·탐지 모드 선행 운영으로 통제하는 것이 설계의 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IDS·IPS 아키텍처 차이 | Out-of-band(SPAN/TAP) vs In-line(Bridge), 가용성 영향 | "IDS는 탐지, IPS는 차단" 단순 정의 나열 |
| 탐지 기법 트레이드오프 | 오용(Signature, 낮은 FP) vs 이상(Anomaly, 제로데이 탐지) | 특정 기법의 완벽성 주장 |
| In-line 리스크 통제 | SPOF(Bypass), 오탐(탐지 모드 선행), Latency(NPU) | 보안성만 강조, 가용성 간과 |

> 요약: IDS/IPS 문제는 탐지 기법이 아니라 "망 구성(In-line vs Out-of-band)"과 "오탐·장애 통제력"을 묻는 아키텍처 문제임.

## Ⅰ. 개요 및 필요성

- 개요: 네트워크 트래픽·호스트 로그를 시그니처·행위 기반으로 분석하여 침입을 탐지(IDS)하거나 실시간 차단(IPS)하는 보안 솔루션임.
- 배경: 방화벽(023)의 허용 포트(80·443)를 통과하는 L7 공격(SQLi·XSS·버퍼 오버플로우)이 증가함.
- 필요성: 알려진 공격 시그니처 방어와 미지의 제로데이 이상 행위 탐지를 병행하는 2차 방어선이 필수임.

---

## Ⅱ. 구조 및 구성요소

```text
[IDS 구조: Out-of-band]                    [IPS 구조: In-line]
Router -> Switch(SPAN/TAP) -> Firewall      Router -> IPS(Bridge) -> Firewall
              |                                         |
              +-> IDS(트래픽 복사본 분석)              (직접 트래픽 통과·차단)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 센서(Sensor) | 트래픽 캡처 및 1차 패턴 매칭 | NIDS(네트워크), HIDS(호스트) 구분 |
| 분석기(Analyzer) | 오용·이상 탐지 알고리즘으로 침입 판단 | ML 기반 UBA(User Behavior Analytics) 통합 추세 |
| 정책 관리(Manager) | 시그니처 DB 업데이트·경보 설정 | Snort·Suricata 개방형 룰셋 호환 |
| 차단 엔진(IPS 한정) | 악성 패킷 Drop, TCP RST 전송, 방화벽 동적 연동 | Latency 최소화가 핵심 설계 요소 |

> 요약: IDS는 SPAN/TAP으로 복사본을 받아 분석하고, IPS는 트래픽 경로상에서 직접 분석·차단을 수행함.

---

## Ⅲ. 동작원리 및 흐름도

```text
트래픽 유입 -> 패킷 정규화(단편화 조립) -> 오용 탐지(시그니처 매칭) -> 이상 탐지(베이스라인 이탈) -> 침입 판단 -> [IDS: 경보] / [IPS: Drop+RST]
```

1. 패킷 수집·정규화: IP 단편화를 재조립하고 프로토콜을 디코딩하여 회피 공격(fragmentation evasion)을 방지함.
2. 오용 탐지(Signature): 시그니처 DB(Snort 룰 등)와 패턴 매칭하여 알려진 공격을 빠르게 식별함. 정규표현식 기반으로 FP가 낮으나 제로데이는 미탐함.
3. 이상 탐지(Anomaly): 학습된 정상 베이스라인(세션 수·프로토콜 비율)과 비교하여 이탈 트래픽을 탐지함. 미지의 공격을 잡을 수 있으나 FP율이 높음.
4. 정책 대응: IDS는 경보(이메일·SIEM 전송)만 발생하고, IPS는 패킷 Drop + TCP RST 전송 + 방화벽 차단 룰 동적 추가를 수행함.

> 요약: 시그니처(정확성)와 이상 탐지(커버리지)를 순차 적용하며, IDS는 경보, IPS는 실시간 차단으로 대응 방식이 갈림.

---

## Ⅳ. 특징

- 오용 탐지 강점: 알려진 공격 패턴에 FP가 낮고 처리 속도가 빠르나, 시그니처 DB에 없는 제로데이·변종 공격은 미탐(FN)함.
- 이상 탐지 강점: 미지의 공격·제로데이 탐지가 가능하나, 정상 트래픽 급증(세일·이벤트)을 공격으로 오인하는 높은 FP율이 약점임.
- 하이브리드 적용: 오용+이상 탐지를 병행하여 FP·FN을 동시에 줄이는 것이 실무 표준이며, ML 기반 UBA로 정밀도를 향상시키는 추세임.
- IPS In-line 리스크: 장비 장애 시 트래픽 전면 차단(SPOF)되므로 Hardware Bypass(Fail-open)가 필수이고, 오탐 시 서비스 중단이 발생하므로 탐지 모드 선행 운영 후 차단 전환함.

> 요약: 오용 탐지는 정확성(가용성), 이상 탐지는 커버리지(보안성)에 강하며, IPS는 가용성 리스크 통제가 핵심임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | NIDS (네트워크 기반) | HIDS (호스트 기반) | 선택 기준 |
|:---|:---|:---|:---|
| 감시 영역 | 네트워크 세그먼트 전체 트래픽 | 개별 서버의 로그·파일 무결성·프로세스 | 보호 대상의 위치·범위 |
| 암호화 대응 | TLS 암호화 시 Payload 분석 불가(복호화 키 필요) | 호스트에서 복호화된 데이터 직접 분석 가능 | TLS 1.3 적용 여부 |
| 확장성 | 세그먼트 단위 센서 배치 | 서버마다 에이전트 설치 | 서버 수·운영 부하 |

> 요약: TLS 1.3 보편화로 NIDS의 Payload 가시성이 저하되므로, HIDS(EDR)를 병행하여 호스트 단 가시성을 확보해야 함.

**리스크·대응:**
- IPS 장비 장애(SPOF): In-line 장비 HW/SW 결함 시 트래픽 전면 차단 → Hardware Bypass(Fail-open) 적용 (지표: 장비 다운 시 패킷 통과 여부)
- 오탐(FP) 업무 마비: 엄격한 룰·베이스라인 변화로 정상 트래픽 차단 → IDS 모드(Monitor) 선행 운영 후 IPS 차단 전환, 예외 정책 세분화 (지표: FP 건수·정탐률)
- 패킷 처리 지연: 복잡한 정규식 엔진·대용량 트래픽 → NPU/FPGA 가속, 불필요한 시그니처 비활성화 (지표: p99 Latency)

**점검 지표:**
- 보안: 탐지율(Detection Rate) — 알려진 공격 패턴 기준 99% 이상 목표
- 가용성: In-line IPS의 Bypass 전환 시간 — 장비 장애 시 10ms 이내

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 계층 방어 배치: 외곽 방화벽(023) 후단에 IPS를 In-line으로 배치하되, Bypass 스위치를 연동하여 장비 장애 시에도 가용성 99.99%를 확보함.
2. TLS 가시성 확보: TLS 1.3 환경에서 NIDS의 Payload 분석이 불가하므로, SSL 복호화 전용 장비(SSL VA)를 IDS 앞단에 배치하여 평문 트래픽을 공급함.
3. SOAR 자동 대응: IDS/IPS 경보를 SIEM(118)으로 수집하고, SOAR(119) 플레이북으로 위협 IP를 방화벽 차단 리스트에 자동 추가하여 대응 시간을 수분 이내로 단축함.

**결론:**
- 기술사 판단: IDS/IPS는 탐지 기법(시그니처·행위)보다 In-line 구성의 가용성 리스크(SPOF·오탐)를 얼마나 정밀하게 통제하는지가 설계의 성패를 결정함.
- 향후 방향: 독립 IDS/IPS 장비는 NGFW에 통합되고, 호스트 단은 EDR/XDR 형태로 전환되어 컨텍스트 기반 위협 헌팅·자동 대응으로 진화하는 추세임.
