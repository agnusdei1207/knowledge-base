## Ⅰ. 개요
- **정의**: 소프트웨어 기반으로 WAN 연결을 중앙 제어·최적화하는 네트워크 기술
- **배경/필요성**: MPLS 전용선 비용이 높고, 클라우드·SaaS 트래픽 증가로 유연한 WAN 관리가 필요함
- **비유**: 여러 택배사 노선을 하나의 관제탑에서 화물 종류별로 최적 배분하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MPLS 대비 SD-WAN의 차별점과 아키텍처 | 오버레이 기반 다중 회선 활용과 중앙 정책 관리 | SD-WAN은 MPLS 대체가 아닌 보완·병행 관계임을 구분할 것 |

> 요약: 다중 WAN 회선을 소프트웨어 정책으로 중앙 제어하여 비용과 유연성을 개선하는 기술임

## Ⅱ. 구성요소
```text
Central Controller (Orchestrator)
        |
   +----+----+
   |         |
 vEdge-A   vEdge-B
   |         |
MPLS/Internet/LTE (Underlay)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Orchestrator | 정책 정의·배포·모니터링을 수행하는 중앙 관리 플랫폼 | 관제탑의 운항 관리 시스템 |
| vEdge/CPE | 지점에 설치되어 오버레이 터널을 생성하는 엣지 장비 | 각 물류 거점의 자동 분류기 |
| Overlay | IPsec/GRE 터널로 구성된 논리적 WAN 네트워크 | 물리 도로 위에 그린 가상 전용 차선 |
| Underlay | MPLS·인터넷·LTE 등 실제 물리 회선 | 실제 고속도로·국도·항공 노선 |

> 요약: Orchestrator·vEdge·Overlay·Underlay 4계층 구조로 WAN을 추상화함

## Ⅲ. 절차
```text
정책 정의 --> vEdge 프로비저닝 --> 오버레이 구성 --> 트래픽 분배 --> 실시간 최적화
```
- 1단계: Orchestrator에서 애플리케이션별 QoS·보안 정책을 정의함
- 2단계: Zero-Touch Provisioning으로 지점 vEdge를 자동 설정함
- 3단계: vEdge 간 암호화 터널(Overlay)을 구성하여 논리 망을 생성함
- 4단계: 실시간 회선 품질 측정 결과에 따라 트래픽을 최적 경로로 동적 분배함

> 요약: 정책 정의부터 동적 트래픽 분배까지 4단계로 WAN을 자동 최적화함

## Ⅳ. 문제점
- 보안 경계 변화: 인터넷 직접 연결(DIA) 확대로 지점별 보안 위협 노출 면이 증가함
- 레거시 호환: 기존 MPLS 인프라와의 공존 과도기에 이중 관리 부담이 발생함
- 벤더 종속: 벤더별 독자 프로토콜로 멀티벤더 환경 구성이 제한됨

> 요약: 보안·레거시 호환·벤더 종속이 SD-WAN 도입의 주요 과제임

## Ⅴ. 개선방안
1. 단기: SASE(Secure Access Service Edge) 통합으로 지점 보안을 클라우드에서 일원화함
2. 중기: MPLS-SD-WAN 하이브리드 아키텍처로 점진적 전환하여 이중 관리를 축소함
3. 장기: 표준 API·오픈 프로토콜 기반 멀티벤더 상호운용성을 확보함

> 요약: SASE 통합·하이브리드 전환·표준화로 단계적 개선이 가능함

## Ⅵ. 전망
- 발전 방향: SASE와 융합하여 네트워크+보안 통합 서비스로 진화함
- 기술사적 판단: 클라우드 중심 WAN의 표준 아키텍처로 자리잡고 있으며 MPLS 엣지 대체가 가속됨
- 기술사 제언: SASE·ZTNA와의 연계 구조, MPLS 대비 TCO 분석 관점을 함께 준비할 필요
