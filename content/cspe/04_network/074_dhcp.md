## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 네트워크에 접속한 단말에게 IP 주소, 서브넷 마스크, 게이트웨이 등의 네트워크 설정 정보를 동적으로 할당하는 프로토콜 |
| **배경/필요성** | 수동 IP 관리로 인한 주소 충돌 방지 및 대규모 망에서의 모바일 단말(노트북, 폰) 이동성 지원 필요 |
| **출제 의도** | DHCP 4단계 통신(DORA) 절차와 임대(Lease), 갱신(Renew) 메커니즘 동작 이해 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Client  |       | Network  |       |   DHCP   |
| (No IP)  | <---> | (Switch) | <---> |  Server  |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Discover (발견) | IP가 없는 클라이언트가 DHCP 서버를 찾기 위해 브로드캐스트하는 메시지 | 신입사원의 부서 질문 |
| Offer (제공) | 서버가 사용 가능한 IP 풀(Pool)에서 주소를 가할당하여 클라이언트에게 제시 | 관리자의 가승인 답변 |
| Lease (임대) | 할당된 IP 주소의 사용 기한으로 주기적인 갱신(Renew) 통신 요구됨 | 도서관 책 대출 기간 |

> 요약: 네트워크 관리자의 개입 없이 단말 접속 시 즉각적인 플러그 앤 플레이(PnP) 통신을 가능하게 함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| Discover | -> |  Offer   | -> | Request  | -> |   ACK    |
+----------+    +----------+    +----------+    +----------+
```
1. Discover: 클라이언트가 전체 망(255.255.255.255)에 DHCP 서버 탐색 메시지 브로드캐스트
2. Offer: 요청을 수신한 서버(들)가 사용 가능한 IP 및 환경 설정 제안 패킷 응답
3. Request: 클라이언트가 여러 제안 중 하나를 선택하여 해당 서버에 IP 확정 사용 요청
4. ACK: 해당 서버가 IP 사용을 최종 승인(임대 시간 포함)하며, 단말은 네트워크 설정 완료

> 요약: D.O.R.A 4단계의 신속한 핸드쉐이크를 통해 IP 충돌 없이 안전한 주소 임대 수행

## Ⅳ. 문제점
- DHCP 요청이 브로드캐스트라 라우터를 넘어가지 못해 다른 서브넷의 단말 수용 불가 (단절 문제)
- 악의적인 해커가 가짜(Rogue) DHCP 서버를 구축하여 엉뚱한 게이트웨이 할당 시 트래픽 탈취(MITM) 가능
- 다수 단말이 동시에 재부팅 시(정전 복구 등) 브로드캐스트 폭풍 발생으로 일시적 망 마비 우려

## Ⅴ. 개선방안
- [단기] 라우터에 DHCP Relay Agent(IP Helper)를 설정하여 브로드캐스트를 유니캐스트로 중계
- [중기] 스위치에 DHCP Snooping 보안 설정 활성화로 인가되지 않은 가짜(Rogue) DHCP 서버 패킷 차단
- [장기] 고정 IP 및 동적 IP 풀을 통합 모니터링하는 전문 IPAM(IP 주소 관리) 자동화 솔루션 도입 구축

## Ⅵ. 전망
- IoT 단말 폭증에 대비하여 IPv6 환경의 동적 할당 체계(SLAAC)로 점진적 전환될 전망임
