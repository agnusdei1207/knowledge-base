## 미리 알고가기

- 듀얼 스택: 장비가 IPv4와 IPv6를 동시에 구성해 목적지에 맞는 프로토콜을 쓰는 방식임
- 터널링: IPv6 패킷을 IPv4 안에 캡슐화하거나 반대로 감싸 기존 망을 통과시키는 방식임
- 변환: IPv4와 IPv6 헤더와 주소를 중간 장비가 서로 바꿔 주는 방식임
- NAT64/DNS64: IPv6 단말이 IPv4 서버에 접근할 수 있도록 주소와 DNS 응답을 변환하는 조합임

## Ⅰ. 개요

- **정의/개념**: IPv6 전환 기술은 IPv4와 IPv6가 공존하는 기간에 단말, 네트워크, 서비스 간 통신을 유지하기 위한 듀얼 스택, 터널링, 변환 방식임
- **배경/필요성**: IPv6를 한 번에 전면 적용하기 어렵고 IPv4 서비스가 남아 있으므로 단계별 공존과 상호 접속 절차가 필요함

## Ⅱ. 특징

- 듀얼 스택은 양쪽 프로토콜을 모두 운영하므로 호환성은 높지만 주소와 보안 정책을 두 벌 관리해야 함
- 터널링은 중간 IPv4 망을 그대로 통과할 수 있지만 캡슐화 오버헤드와 MTU 문제를 확인해야 함
- 변환은 한쪽 프로토콜만 쓰는 단말을 연결하지만 주소 변환 상태와 응용 호환성 제약이 생김
- 전환 방식은 망 구간, 단말 지원, 서비스 대상에 따라 조합해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 듀얼 스택 | 터널링 | 변환 |
|:---|:---|:---|:---|
| 동작 방식 | IPv4와 IPv6를 동시에 구성함 | 한 프로토콜 패킷을 다른 프로토콜 안에 감쌈 | 헤더와 주소를 중간 장비가 바꿈 |
| 적용 조건 | 장비와 회선이 두 프로토콜을 모두 지원해야 함 | 중간망이 목적 프로토콜을 직접 지원하지 않아도 됨 | 통신 양끝이 서로 다른 프로토콜만 지원할 때 씀 |
| 운영 부담 | 라우팅, 보안, 모니터링 정책이 두 벌 필요함 | MTU, 경로 추적, 캡슐화 장애를 확인해야 함 | 상태 테이블, DNS 변환, 응용 프로토콜 호환성을 관리해야 함 |
| 대표 기술 | Native IPv4/IPv6 병행 | 6in4, GRE, 6rd | NAT64, DNS64, 464XLAT |

> 요약: 듀얼 스택은 병행 운영, 터널링은 경유, 변환은 상호 접속 문제를 해결하는 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IPv4/IPv6 라우팅 | 각 프로토콜의 경로를 별도로 계산하거나 전환 장비까지 전달함 |
| 전환 게이트웨이 | 터널 종단이나 변환 지점이 되며 주소와 세션 상태를 관리함 |
| DNS 연동 | 목적지 주소 선택과 DNS64 변환이 접속 가능 여부를 좌우함 |
| 보안 정책 | IPv4와 IPv6 정책 불일치가 우회 경로가 되지 않도록 통제함 |

```text
+----------+      +--------------+      +----------+
| IPv6 Host| ---> | Transition GW| ---> | IPv4 Svc |
+----------+      +--------------+      +----------+
        tunnel or translation
```

> 요약: 전환 구조는 단말 지원, 게이트웨이 위치, DNS 응답, 보안 정책이 함께 맞아야 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 대상확인  | --> | 방식선택  | --> | 패킷처리  | --> | 접속검증 |
+----------+     +----------+     +----------+     +----------+
```

1. **대상확인**: 단말, 경로, 서비스가 IPv4와 IPv6 중 무엇을 지원하는지 확인함
2. **방식선택**: 양쪽 지원이면 듀얼 스택, 중간망 제약이면 터널링, 상호 불일치면 변환을 선택함
3. **패킷처리**: 선택 방식에 따라 원 패킷을 그대로 보내거나 캡슐화 또는 주소 변환함
4. **접속검증**: DNS 응답, MTU, 세션 로그, 경로 추적으로 정상 접속을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 기업망 전환은 듀얼 스택부터 적용하되 IPv6 방화벽 정책이 누락되면 우회 접속이 생기므로 IPv4와 IPv6 정책을 같은 서비스 단위로 맞추고 차단 로그와 라우팅 테이블로 확인함
2. NAT64나 464XLAT을 쓰는 모바일망에서는 DNS64 응답과 변환 상태가 맞지 않으면 특정 앱만 실패하므로 도메인별 AAAA 응답, 변환 세션 수, 앱 오류 로그로 확인함

## Ⅶ. 결론

IPv6 전환은 한 가지 기술의 우열 문제가 아니라 남아 있는 IPv4 서비스와 IPv6 단말을 어떤 구간에서 연결할지 정하는 절차임.

## 작성 근거(검토용)

- 전환 기술은 속도 비교가 아니라 공존 구간의 연결 절차이므로 방식별 적용 조건과 운영 부담을 비교함
- 접속 가능 여부는 방식별 제약이 있어 DNS, MTU, 세션 로그 같은 검증 항목으로 풀어 씀
- 결론은 듀얼 스택, 터널링, 변환을 망 구간별 선택 문제로 회수함
