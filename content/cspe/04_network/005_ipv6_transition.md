## Ⅰ. 개요
- **정의**: IPv4에서 IPv6로의 전환을 위한 듀얼스택·터널링·변환 기술의 총칭임
- **배경/필요성**: IPv4 주소 고갈(004 참조) 상황에서 기존 인프라와의 호환을 유지하며 IPv6로 이행해야 함
- **비유**: 좌측통행 도로를 우측통행으로 바꿀 때 혼합 차선을 운영하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3가지 전환 기법 비교 | 듀얼스택·터널링·변환의 동작 원리 차이 | 각 기법의 적용 시나리오와 한계를 구분하여 기술 |

> 요약: IPv6 전환은 듀얼스택·터널링·변환 3가지 방식으로 호환성을 확보함

## Ⅱ. 구성요소
```text
[IPv4 망] --터널링--> [IPv6 망]
    |                     |
    +---듀얼스택 노드---+
    |                     |
[IPv4 호스트] --변환(NAT64)--> [IPv6 호스트]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 듀얼스택 | 하나의 장비에서 IPv4·IPv6를 동시 운영함 | 이중 언어 통역사 |
| 터널링 | IPv6 패킷을 IPv4 패킷으로 캡슐화하여 전송함(6to4, ISATAP) | 기존 도로 위에 고가도로 건설 |
| 변환(NAT64/DNS64) | IPv4↔IPv6 간 헤더를 변환하여 상호 통신을 지원함 | 동시통역기 |

> 요약: 듀얼스택은 병행, 터널링은 캡슐화, 변환은 헤더 치환으로 전환을 지원함

## Ⅲ. 절차
```text
현황 분석 --> 전환 방식 선정 --> 단계 적용 --> 단일 스택 전환
```
- 1단계: 현황 분석 — 기존 IPv4 장비·애플리케이션 호환성을 점검함
- 2단계: 전환 방식 선정 — 네트워크 규모·트래픽 특성에 따라 듀얼스택/터널링/변환을 결정함
- 3단계: 단계 적용 — 코어 → 에지 → 엔드포인트 순서로 IPv6를 활성화함
- 4단계: 단일 스택 전환 — IPv4 의존성 제거 후 IPv6 단일 운영으로 전환 완료함

> 요약: 현황 분석 → 방식 선정 → 단계 적용 → 단일 전환 순으로 진행함

## Ⅳ. 문제점
- 듀얼스택 비용: 이중 프로토콜 운영 — 라우팅 테이블·보안 정책을 2벌 관리해야 함
- 터널링 오버헤드: 캡슐화 처리 — MTU 감소와 단편화로 전송 지연 증가
- 변환 기능 제한: NAT64 한계 — IPv6 전용 기능(확장 헤더)을 IPv4로 완전 매핑 불가

> 요약: 이중 관리 비용, 캡슐화 오버헤드, 변환 기능 제한이 전환의 장벽임

## Ⅴ. 개선방안
1. 단기: 자동화 도구로 듀얼스택 정책 동기화를 수행하여 관리 부담 경감
2. 중기: MAP-E/MAP-T 등 경량 터널링 기술 도입으로 오버헤드 절감
3. 장기: 464XLAT 등 통합 변환 프레임워크로 엔드투엔드 IPv6 통신 보장

> 요약: 정책 자동화 → 경량 터널링 → 통합 변환 프레임워크로 전환 장벽을 해소함

## Ⅵ. 전망
- 발전 방향: 클라우드·5G 인프라의 IPv6 기본 채택으로 전환 속도가 가속화됨
- 기술사적 판단: 전환 기술은 과도기 수단이며 최종 목표는 IPv6 단일 스택임
- 기술사 제언: 공공·민간 신규 사업 시 IPv6 단일 설계를 기본 요건으로 명시할 것을 제안함
