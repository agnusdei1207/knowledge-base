# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: IPv6 전환 기술은 IPv4·IPv6가 **직접 통신할 수 없는 비호환** 문제를 공존 기간 동안 이어주는 상호운용 기법으로, **듀얼 스택(Dual Stack)·터널링(Tunneling)·변환(Translation)** 세 가지가 축이다.
- **왜 필요한가**: IPv4와 IPv6는 헤더 구조가 다른 별개 프로토콜(004 참조)이라, IPv6 단말이 IPv4 세상과 곧바로 대화할 수 없어 다리 역할이 필요하기 때문이다.
- **핵심 직관**: 듀얼 스택="양쪽 언어를 둘 다 할 줄 아는 사람", 터널링="다른 나라를 지날 때 우리 편지를 그 나라 봉투에 넣어 보냄", 변환="통역사가 말 자체를 바꿔줌".

## 핵심 용어 정리 (내부에 등장하는 것들)

IPv4·IPv6의 주소 구조·헤더·NAT 기본은 004·011에서 다뤘으므로, 여기서는 전환 메커니즘에 직결된 용어를 정리한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 듀얼 스택 (Dual Stack) | 한 노드가 IPv4·IPv6 프로토콜 스택을 동시에 탑재해 상대에 맞춰 선택 | 2개 국어를 둘 다 구사하는 사람 |
| 터널링 (Tunneling) | 한 프로토콜 패킷을 다른 프로토콜 패킷 안에 통째로 감싸(캡슐화) 전달 | 편지를 다른 나라 봉투에 넣어 그 나라 우편망으로 배송 |
| 캡슐화 (Encapsulation) | IPv6 패킷을 IPv4 헤더로 감싸 IPv4 망을 통과시키는 것 | 소포를 더 큰 상자에 다시 포장 |
| 변환 (Translation) | 헤더·주소를 상대 프로토콜 형식으로 실제로 바꿔주는 것 | 통역사가 문장을 다른 언어로 번역 |
| NAT64 | IPv6 단말이 IPv4 서버에 접속하도록 IPv6↔IPv4 주소·헤더를 변환 | IPv6→IPv4 방향 통역 게이트웨이 |
| DNS64 | IPv4 전용 도메인 응답(A레코드)을 IPv6 주소(AAAA)로 합성해 NAT64로 유도 | 통역사에게 갈 수 있게 주소를 미리 바꿔주는 안내 |
| 6to4 / 6rd | IPv6 패킷을 IPv4 망 위로 자동 터널링하는 초기·개선 방식 | IPv4 고속도로에 IPv6 화물을 실어 나름 |
| ISATAP | 사이트 내부 IPv4 망에서 IPv6 노드 간 터널링 | 건물 내부용 IPv6 임시 통로 |
| 464XLAT | 모바일망에서 IPv4 앱 트래픽을 IPv6로 실어 NAT64로 넘기는 방식 | IPv4 앱을 IPv6 도로에 태워 통역소로 보냄 |
| 프로토콜 41 | IPv6-in-IPv4 터널을 나타내는 IP 프로토콜 번호 | 터널 전용 봉투에 찍힌 도장 |
| MTU / 프래그먼트 | 캡슐화로 헤더가 늘어 전송 단위를 초과하면 조각내야 함 | 상자가 커져 규격 초과 시 나눠 포장 |

## 깊이 이해
- **배경·문제의식**: IPv4 고갈로 IPv6가 필요하지만, 전 세계 IPv4 인프라·서버를 하루아침에 바꿀 수 없다. IPv4와 IPv6는 헤더 필드가 다른 별개 프로토콜이라 라우터·단말이 상대 패킷을 해석하지 못한다. 따라서 "플래그 데이(전면 교체)"가 아니라 **수십 년의 공존**을 전제로, 두 세계를 이어줄 전환 기법이 설계됐다.
- **작동 원리(어떻게+왜)**:
  - **듀얼 스택**: 노드가 IPv4·IPv6 주소를 모두 갖고, 통신 상대가 IPv6면 IPv6로, IPv4면 IPv4로 스택을 골라 쓴다. 변환·터널 없이 가장 단순·완전하지만, 공인 IPv4 주소가 여전히 필요하고 두 스택을 모두 운영·보안 관리해야 한다.
  - **터널링**: IPv6 섬(island)들이 중간의 IPv4 바다로 분리돼 있을 때, IPv6 패킷을 IPv4 헤더로 감싸(프로토콜 41) IPv4 망을 건너게 한다. 반대(IPv4-in-IPv6)도 가능하다. 경로 중간 장비는 IPv4 패킷으로만 보므로 통과시킨다. 단, 헤더가 늘어 MTU 초과·프래그먼트 문제가 생긴다.
  - **변환(NAT64/DNS64)**: 한쪽이 IPv6 전용, 상대가 IPv4 전용이라 공통 스택이 없을 때 쓴다. DNS64가 IPv4 서버의 A레코드를 IPv6(AAAA)로 합성해 IPv6 단말을 NAT64 게이트웨이로 유도하고, NAT64가 헤더·주소를 실제로 IPv4로 번역해 전달한다. 주소를 아끼는 대신 헤더 변환으로 종단 간 IPSec·일부 응용이 깨질 수 있다.
- **비유**: 세 기법은 국경 통행에 비유된다. 듀얼 스택=여권 2개(양국 시민권)를 가진 사람, 터널링=우리 편지를 상대국 봉투에 넣어 그 나라 우편망으로 부치기, 변환=말과 글을 실제로 바꿔주는 통역사.
- **구체 예시**:
  - 듀얼 스택: 서버가 `A=203.0.113.10`과 `AAAA=2001:db8::10`을 함께 광고 → IPv6 클라이언트는 AAAA로, IPv4 클라이언트는 A로 접속.
  - 터널링(6rd): 가정 IPv6 단말의 패킷을 ISP 경계에서 IPv4로 캡슐화해 IPv4 백본을 건너고, 반대편에서 벗겨 IPv6로 복원.
  - NAT64/DNS64: IPv6 전용 스마트폰이 IPv4 전용 사이트에 접속 시, DNS64가 `64:ff9b::cb00:710b` 형태의 합성 주소를 반환하고 NAT64가 이를 실제 IPv4로 번역.
- **흔한 오해·주의점**: 세 기법은 우열이 아니라 **상황별 선택**이다. 듀얼 스택이 가장 깔끔하나 IPv4 주소를 계속 소모하고, 변환은 주소를 아끼지만 종단 간 투명성·IPSec을 해친다. "전환 기술을 쓰면 IPv6로 완전히 넘어간 것"이 아니라, 공존 상태를 견디게 해주는 임시 다리다. 터널은 캡슐화로 MTU가 줄어 Path MTU Discovery·프래그먼트 처리를 반드시 고려해야 한다.

## 연결 개념
- IP 주소 체계(004) — IPv4/IPv6 비호환이라는 전환의 근본 원인
- NAT/PAT(011) — 변환(NAT64)의 뿌리가 되는 주소 변환 메커니즘
- 캡슐화·터널(VPN 111) — 패킷을 다른 패킷에 감싸는 동일 원리

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IPv6 전환 기술은 IPv4·IPv6 비호환을 공존 기간 동안 잇는 상호운용 기법으로 듀얼스택·터널링·변환으로 나뉨.
> 2. **가치**: 전면 교체(플래그 데이) 없이 점진 전환을 가능케 해 서비스 연속성과 IPv4 자산 재활용을 보장함.
> 3. **판단 포인트**: IPv4 주소 여유·종단 투명성 요구·망 구간에 따라 세 기법을 조합 적용하는 것이 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세 전환 기법 구분 이해 | 듀얼스택·터널링·변환의 원리·적용 조건 | 세 기법을 우열로 단정, 상황 판단 결여 |
| 변환 메커니즘 정확 이해 | NAT64+DNS64 연동, IPv6→IPv4 방향 | NAT64와 일반 NAT 혼동, DNS64 역할 누락 |
| 전환 리스크 인식 | MTU·프래그먼트, IPSec·투명성 저하 | 터널의 캡슐화 오버헤드·보안 영향 누락 |

> 요약: 기법 나열이 아니라 IPv4 주소 여유·투명성 요구에 따른 선택 기준을 판단으로 서술함.

---

## Ⅰ. 개요 및 필요성

- 개요: IPv4·IPv6 비호환 구간을 공존 기간 동안 잇는 상호운용 기법(듀얼스택·터널링·변환)임
- 배경: (004 참조) IPv4·IPv6는 헤더가 다른 별개 프로토콜이라 직접 통신이 불가한 한계
- 필요성: 전 세계 IPv4 인프라를 일시 교체할 수 없어, 서비스 중단 없이 점진 전환을 이루기 위함

---

## Ⅱ. 구조 및 구성요소

```text
[듀얼스택]  노드 = IPv4 스택 + IPv6 스택  → 상대에 맞춰 선택 전송
[터널링]    IPv6 패킷 → [IPv4 헤더로 캡슐화] → IPv4 망 통과 → 디캡슐화 → IPv6 복원
[변환]      IPv6 단말 → DNS64(주소 합성) → NAT64(헤더·주소 번역) → IPv4 서버
```

| 구성요소 | 개념 | 주요 역할 | 대표 방식 |
|:---|:---|:---|:---|
| 듀얼 스택 | 두 프로토콜 동시 탑재 | 상대 버전에 맞춰 무변환 통신 | Dual Stack, DS-Lite |
| 터널링 | 다른 프로토콜로 캡슐화 | IPv4 망 위로 IPv6 섬 연결 | 6to4·6rd·ISATAP·프로토콜41 |
| 변환 | 헤더·주소 실제 번역 | IPv6 전용↔IPv4 전용 중계 | NAT64+DNS64·464XLAT |

> 요약: 듀얼스택은 병행 운영, 터널링은 캡슐화 통과, 변환은 헤더 번역으로 각기 다른 공존 구간을 담당함.

---

## Ⅲ. 동작원리 및 흐름도

```text
통신 개시 → 상대 주소 확인(A/AAAA) → [둘 다 지원=듀얼스택] or [중간 IPv4망=터널] or [전용 상대=변환] → 전달
```

1. **경로 판단**: 노드가 DNS로 상대의 A(IPv4)·AAAA(IPv6) 레코드를 조회해 사용할 프로토콜을 결정함
2. **듀얼스택 처리**: 양측이 공통 버전을 가지면 변환 없이 해당 스택으로 직접 송수신함
3. **터널 캡슐화**: IPv6 구간이 IPv4 망으로 단절되면 IPv6 패킷을 IPv4 헤더로 감싸 통과 후 반대편에서 벗김
4. **변환 중계**: IPv6 전용 단말이 IPv4 서버 접속 시 DNS64가 주소를 합성하고 NAT64가 헤더를 번역해 중계함

> 요약: 상대 버전·중간 망 구성을 판단해 무변환(듀얼스택)·캡슐화(터널)·번역(변환) 중 최적 경로를 택함.

---

## Ⅳ. 특징

- 점진성: 플래그 데이 없이 구간별로 도입해 서비스 연속성을 유지함
- 조합 적용: 하나만 쓰지 않고 코어=듀얼스택, 액세스=변환처럼 구간별로 혼합함
- 터널 오버헤드: 캡슐화로 헤더가 늘어 MTU 감소·프래그먼트·Path MTU 이슈가 발생함
- 변환의 투명성 저하: NAT64는 종단 간 IPSec·IP 임베디드 응용(SIP·FTP)을 깨뜨릴 수 있음
- 주소 절약 vs 완결성: 변환은 IPv4 주소를 아끼나, 듀얼스택은 완전하되 IPv4 주소를 계속 소모함

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 듀얼 스택 | 터널링 | 변환(NAT64) |
|:---|:---|:---|:---|
| 원리 | 두 스택 병행 | 캡슐화 통과 | 헤더·주소 번역 |
| IPv4 주소 | 계속 필요 | 필요(엔드포인트) | 절약(공유) |
| 종단 투명성 | 높음 | 중간(캡슐화) | 낮음(번역) |
| 적용 구간 | 코어·서버 | IPv6 섬 연결 | IPv6 전용 액세스 |
| 한계 | 이중 운영 부담 | MTU·프래그먼트 | IPSec·응용 호환 |

> 요약: 주소 여유가 있으면 듀얼스택, 섬 연결은 터널, IPv6 전용망은 변환으로 구간별 최적 조합이 정답임.

- 터널 리스크: 캡슐화 오버헤드로 조각화·성능 저하 → MTU 조정·Path MTU Discovery 적용
- 변환 리스크: 종단 IPSec·IP 참조 응용 파손 → ALG 적용 또는 듀얼스택 병행으로 회피
- 관리 지표: IPv6 트래픽 비율, NAT64 세션 사용률, 터널 재조립 실패율

---

## Ⅵ. 실무 적용 및 결론

- 구간별 조합 설계: 코어·서버는 듀얼스택, 모바일 액세스는 464XLAT/NAT64로 분리 적용함
- 모바일 IPv6화: 이동통신망은 IPv6 단일망 + NAT64/DNS64로 IPv4 앱 호환을 확보함
- 전환 모니터링: IPv6 도달률·NAT64 세션·터널 오류를 대시보드로 추적해 단계적 IPv4 축소를 판단함
- 결론(조건부 판단): 공인 IPv4 여유가 있으면 듀얼스택 우선, 부족하면 NAT64+DNS64로 IPv6 단일망 전환이 유리함
- 결론(향후 방향): IPv6 도입률 상승으로 최종 목표는 IPv6-only이며, 전환 기술은 잔존 IPv4 호환을 위한 과도기 수단임
