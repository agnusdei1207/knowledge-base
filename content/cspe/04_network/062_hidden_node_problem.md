## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 서로 전파가 닿지 않는 두 노드가 동시에 한 AP로 전송을 시도하여 충돌하는 현상 |
| **배경/필요성** | 무선 매체 특성상 충돌 감지(CD)가 불가능하여 대역폭 낭비 및 성능 저하 유발 |
| **출제 의도** | 무선 LAN의 반송파 감지 한계와 RTS/CTS 기반의 가상 채널 예약 메커니즘 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Node A  |       |    AP    |       |  Node B  |
| (Hidden) | ----> | (Center) | <---- | (Hidden) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 숨겨진 노드 | AP와는 통신되지만 서로는 감지하지 못하는 단말 | 사각지대 차량 |
| AP (접속점) | 단말 간 무선 신호를 중계하는 중앙 집중 제어 장치 | 교차로 신호등 |
| RTS/CTS | 전송 전 채널 사용권을 요청하고 승인받는 제어 프레임 | 통행 예약권 |

> 요약: 매체 점유 상태를 알리기 위해 RTS/CTS 프레임 교환을 통한 사전 예약이 필요함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 전송 대기| -> | RTS 전송 | -> | CTS 브로드| -> | 데이터전송|
+----------+    +----------+    +----------+    +----------+
```
1. 전송 대기: 단말이 데이터 전송 전 채널 대기(DIFS) 후 유휴 상태 확인
2. RTS 전송: AP를 향해 송신 요청(RTS) 제어 프레임을 전송하여 점유 의사 전달
3. CTS 브로드: AP가 전체 영역에 송신 허용(CTS)을 브로드캐스트하여 타 노드 대기 지시
4. 데이터전송: 채널 예약 권한을 얻은 노드만 충돌 없이 프레임 송신 수행

> 요약: RTS/CTS 교환으로 가상 반송파 감지(NAV)를 설정하여 무선 충돌을 사전 차단함

## Ⅳ. 문제점
- 짧은 패킷에도 RTS/CTS를 남발하여 심각한 무선 대역폭 오버헤드 유발
- CTS를 수신한 다른 노드들이 통신 가능한 상태임에도 불필요하게 송신 대기 (노출된 노드 원인)
- 잦은 채널 경합과 대기 지연으로 인해 실시간 음성(VoIP) 서비스 품질 저하

## Ⅴ. 개선방안
- [단기] 임계값(Threshold) 조정을 통해 대용량 프레임에만 선택적으로 RTS/CTS 적용
- [중기] 지향성 안테나(Directional Antenna) 적용으로 주변 노드 간섭 및 숨겨진 노드 축소
- [장기] OFDMA 기술(Wi-Fi 6)을 도입하여 중앙 AP가 주파수를 분할 스케줄링하여 근본 해결

## Ⅵ. 전망
- 단말 자체 경쟁 방식에서 AP 주도적 스케줄링으로 무선 접근 제어 패러다임이 전환될 것임
