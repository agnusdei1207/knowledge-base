## Ⅰ. 개요
- **정의**: 공유 매체에서 다수의 단말이 데이터 전송 시 충돌을 관리(감지/회피)하기 위한 다중 접속 제어 프로토콜임.
- **배경 및 필요성**: 버스/스타형 토폴로지나 무선 환경에서 두 개 이상의 노드가 동시 송신할 때 발생하는 데이터 손실 방지.
- **출제 의도**: 유선(CD)과 무선(CA) 환경의 물리적 특성 차이에 따른 충돌 제어 메커니즘의 차이점 이해 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **CSMA** | 단말이 매체(채널)를 사용하기 전 통신망이 비어있는지 상태를 확인하는 기능 | 회의실 사용 전 내부 확인 |
| **CD (충돌 감지)** | 유선 환경에서 전송 중 전압 변화를 감지하여 데이터 충돌을 알아채는 방식 | 동시에 말했을 때 즉시 중단 |
| **CA (충돌 회피)** | 무선 환경에서 사전에 제어 메시지(RTS/CTS)를 교환하여 충돌을 회피하는 방식 | 발언권(마이크)을 미리 요청 |

> 요약: CSMA/CD는 유선 이더넷에서 충돌을 감지하고 재전송하며, CSMA/CA는 무선 랜에서 충돌을 사전에 회피함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **상태 확인**: 유무선 공통으로 전송 매체가 유휴 상태(Idle)인지 확인함.
2. **[CD 방식] 감지**: 데이터 전송 중 충돌이 발생하면 잼 신호(Jam)를 보내고 중단함.
3. **[CA 방식] 회피**: 무선에서는 은닉 노드 문제 방지를 위해 송수신 단말 간 RTS/CTS를 교환함.
4. **백오프 대기**: 충돌 감지 또는 채널 점유 시 임의의 시간(Back-off) 대기 후 재시도함.

> 요약: 매체 감지 후 유선은 충돌 감지 후 후퇴하며, 무선은 제어 프레임을 통해 충돌 자체를 회피함.

## Ⅳ. 문제점
- 노드 증가 시 통신 효율 저하 (원인: 충돌 발생 빈도 증가로 인한 지연 시간 누적)
- 무선망 은닉 노드 충돌 (원인: 물리적 거리 장애로 서로 감지하지 못하는 단말 간 동시 송신)
- 제어 오버헤드 (원인: 작은 데이터 전송에도 제어 프레임을 사용하여 대역폭이 낭비됨)

## Ⅴ. 개선방안
- **단기 방안**: [단기] RTS/CTS 임계값 최적화 (일정 크기 이상의 데이터 전송 시에만 사전 제어 교환 적용)
- **중기 방안**: [중기] 전이중 스위치 도입 (유선망에서 충돌 도메인을 분리해 CSMA/CD 메커니즘 최소화)
- **장기 방안**: [장기] OFDMA 등 차세대 접속 적용 (무선 환경 자원을 주파수/공간 분할하여 동시 전송 구현)

## Ⅵ. 전망
- 전이중 통신 및 Wi-Fi 6 다중 접속 기술 발전으로 기존 CSMA 방식의 의존도는 점차 줄어들 전망임.
