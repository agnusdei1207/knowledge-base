## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | TCP 환경에서 패킷 유실을 감지하고 재전송을 결정하기 위한 동적 타이머(Retransmission Timeout) 기법 |
| **배경/필요성** | 네트워크 정체 상태를 고려하지 않은 고정 타임아웃은 혼잡 붕괴나 대역폭 낭비를 초래하므로 적응형 제어 필요 |
| **출제 의도** | RTT(Round Trip Time) 기반의 이동 평균 산출 및 RTO 설정 알고리즘(Jacobson/Karn) 이해 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+
|  Sender  |       | Receiver |
| (Timer)  | <---> | (ACK)    |
+----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| RTT | 특정 세그먼트를 전송하고 상대방의 ACK가 도착하기까지 걸린 실제 소요 시간 | 택배 왕복 시간 |
| SRTT | 단일 RTT의 급격한 튐 현상을 방지하기 위해 가중치를 두어 계산한 이동 평균 | 평균 배송 예측 |
| RTTVAR | RTT의 분산(편차) 값을 구해 네트워크 지터(Jitter) 상태를 반영하는 변수 | 교통 변동성 |

> 요약: 네트워크 환경 변화에 따라 RTT를 지속 관찰하여 최적의 패킷 대기 시간(RTO)을 도출함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 패킷 전송| -> | RTT 측정 | -> | RTO 갱신 | -> | 타임아웃 |
+----------+    +----------+    +----------+    +----------+
```
1. 패킷 전송: 송신 측이 데이터 세그먼트를 발송함과 동시에 재전송 타이머 구동
2. RTT 측정: 정상적인 ACK를 수신하면 샘플 RTT(SampleRTT) 시간 측정
3. RTO 갱신: Jacobson 알고리즘을 사용해 편차(RTTVAR)를 포함한 새로운 RTO 값 동적 갱신
4. 타임아웃: 네트워크 지연이나 손실로 RTO 내에 ACK가 오지 않으면 해당 패킷 재전송

> 요약: RTT 측정과 수학적 보정 알고리즘을 거쳐 정체에 적응하는 능동적 재전송을 수행함

## Ⅳ. 문제점
- 재전송된 패킷의 ACK 수신 시, 이것이 원본 패킷의 ACK인지 재전송 패킷의 ACK인지 구분 모호 (RTT 왜곡 원인)
- 심각한 정체 발생 시 RTO 타이머가 지수적으로 배수 증가(Backoff)하여 심각한 통신 지연 발생
- RTO 만료 전까지는 패킷 유실 여부를 확신할 수 없어 복구(Recovery) 작업 대기 발생

## Ⅴ. 개선방안
- [단기] Karn 알고리즘 적용으로 재전송된 패킷에 대해서는 RTT 측정 샘플에서 완전히 제외
- [중기] TCP Fast Retransmit (3 DUP ACK) 도입으로 긴 RTO 만료 대기 없이 즉각적인 손실 복구
- [장기] TCP SACK(Selective ACK) 옵션을 활용하여 누락된 특정 세그먼트만 정확히 선별 재전송

## Ⅵ. 전망
- 단순 타이머 의존에서 벗어나 BBR처럼 실제 가용 대역폭을 지속 탐색하는 혼잡 제어로 진화할 전망임
