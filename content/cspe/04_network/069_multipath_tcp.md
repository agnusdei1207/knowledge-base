## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 단일 TCP 세션이 여러 네트워크 경로(예: Wi-Fi, LTE/5G)를 동시에 활용하도록 지원하는 전송 확장 프로토콜 |
| **배경/필요성** | 모바일 환경에서 인터페이스 전환 시 발생하는 연결 끊김 극복 및 가용 대역폭의 병합(Aggregation) 필요 |
| **출제 의도** | MPTCP 서브플로(Subflow) 생성 로직 및 다중 경로 환경에서의 혼잡 제어 메커니즘 이해 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|   App    |       |  MPTCP   |       |  Server  |
| (Socket) | <---> | (Subflow)| <---> | (Remote) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| MP-CAPABLE | 최초 연결 시 양단 기기가 MPTCP 기능을 지원하는지 협상하는 TCP 옵션 | 다중 채널 기능 확인 |
| Subflow | 메인 세션 밑에 생성된 각 물리적 인터페이스 기반의 개별 TCP 연결 | 보조 데이터 고속도로 |
| DSN (데이터) | 다양한 경로로 도착한 조각들을 원본 스트림으로 순서 맞게 재조립하기 위한 글로벌 일련번호 | 전체 화물 번호 |

> 요약: 애플리케이션 수정 없이 전송 계층에서 여러 네트워크 인터페이스를 묶어 끊김 없는 통신을 제공함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 연결 수립| -> | 서브 추가| -> | 분산 전송| -> | 데이터합|
+----------+    +----------+    +----------+    +----------+
```
1. 연결 수립: 기본 인터페이스(예: Wi-Fi)로 MP-CAPABLE 옵션을 포함하여 최초 TCP 연결
2. 서브 추가: 추가 인터페이스(예: LTE) 활성화 시 MP-JOIN 메시지로 서브플로 동적 생성
3. 분산 전송: 각 서브플로의 네트워크 상태를 고려하여 트래픽을 동적으로 스케줄링하여 송신
4. 데이터합: 수신 측 MPTCP 계층이 DSN을 기준으로 각기 도착한 패킷들을 순서에 맞게 병합

> 요약: 메인 세션 확립 후 보조 서브플로를 동적으로 추가하여 트래픽을 분산 송수신함

## Ⅳ. 문제점
- Wi-Fi와 LTE 간 RTT(지연) 편차가 클 경우 빠른 경로의 패킷이 수신 버퍼를 꽉 채워 HOL Blocking 발생 원인
- 보안 방화벽 및 중간 NAT 장비가 MPTCP 전용 옵션 헤더를 알 수 없어 패킷을 변조/폐기
- 스마트폰에서 여러 통신 모뎀을 동시 구동하여 배터리 광탈 및 발열 발생 문제

## Ⅴ. 개선방안
- [단기] Active/Backup 모드로 설정하여 평소엔 Wi-Fi만 쓰고 음영 구역에서만 LTE로 전환 구동
- [중기] 통신사 코어망에 MPTCP 프록시를 구축하여 단말과 프록시 구간의 호환성 및 헤더 간섭 완벽 회피
- [장기] 인공지능 기반 지능형 스케줄러 알고리즘(AI-MPTCP) 도입으로 경로별 지연차 실시간 보정

## Ⅵ. 전망
- 5G 네트워크 슬라이싱(ATSSS 구조)과 완벽히 융합되어 최상의 사용자 체감 품질(QoE)을 견인할 전망임
