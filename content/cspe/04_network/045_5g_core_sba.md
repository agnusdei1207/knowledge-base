## 미리 알고가기

- SBA는 5G 코어 기능을 서비스 단위로 나누고 API로 연결하는 구조임
- NF는 AMF, SMF, UPF처럼 각 역할을 맡는 네트워크 기능 단위임
- SBI는 NF 사이에서 HTTP 기반으로 통신하는 서비스 인터페이스임
- CUPS는 제어부와 사용자 데이터 처리부를 분리하는 개념임
- NRF는 어떤 NF가 어디서 동작하는지 등록하고 찾게 해 주는 저장소 역할을 함

## Ⅰ. 개요

- **정의/개념**: 5G 코어 SBA는 이동성 관리, 세션 관리, 정책 제어 같은 코어 기능을 독립된 NF로 분리하고 이들을 서비스 기반 인터페이스로 연결한 5G 코어 구조임
- **배경/필요성**: 4G 코어처럼 장비 간 결합이 강한 구조로는 슬라이싱, 빠른 확장, 클라우드 배치, 엣지 분산 같은 요구를 유연하게 처리하기 어려워서 기능 분리와 API 기반 연결이 필요했음

## Ⅱ. 특징

- 코어 기능을 작게 나눠 필요한 기능만 확장하거나 교체하기 쉬움
- HTTP 기반 SBI를 사용해 서비스 발견, 호출, 정책 연동을 표준화함
- CUPS 덕분에 제어 기능은 중앙에 두고 사용자 데이터 처리는 엣지로 보낼 수 있음
- 유연성이 커진 만큼 NF 간 인증, API 보호, 관측성 확보가 운영 핵심이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 4G EPC 중심 구조 | 5G SBA 구조 |
|:---|:---|:---|
| 기능 결합도 | 장비와 인터페이스 결합이 강해 변경 범위가 큼 | NF가 느슨하게 연결돼 기능 교체와 확장이 쉬움 |
| 연동 방식 | 통신 전용 인터페이스와 점대점 연결이 중심임 | 서비스 호출과 등록 기반의 API 연동이 중심임 |
| 확장 방식 | 장비 단위 증설이 많아 확장 속도가 느림 | NF 단위 확장과 자동화에 유리함 |
| 엣지 배치 유연성 | 사용자면 분리가 제한적이어서 경로 최적화가 덜 유연함 | UPF 분산 배치로 로컬 브레이크아웃 구성이 쉬움 |
| 운영 초점 | 장비 안정성 관리가 중심임 | API 보안, 서비스 발견, 자동화 운영이 중심임 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| AMF | 단말 등록과 이동성 제어를 담당하는 접속 제어 NF임 |
| SMF | 세션 설정과 UPF 선택, IP 경로 제어를 담당하는 세션 관리 NF임 |
| UPF | 실제 사용자 데이터를 전달하고 로컬 브레이크아웃을 수행하는 사용자면 NF임 |
| UDM·PCF | 가입자 정보와 정책 정보를 관리해 인증과 서비스 품질 제어를 지원함 |
| NRF | 어떤 NF가 가동 중인지 등록하고 필요한 NF를 찾게 해 주는 검색 허브임 |

```text
+--------+     +--------+     +--------+     +--------+
| AMF    | --> | SMF    | --> | UPF    | --> | 데이터망 |
+--------+     +--------+     +--------+     +--------+
     \             |             /
      \------------+------------/
             SBI와 정책·등록 연동
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 단말 등록 요청 | --> | AMF 인증 처리 | --> | SMF 세션 생성 | --> | UPF 경로 선택 | --> | 데이터 세션 개통 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **단말 등록 요청**: 단말이 망에 접속하면 AMF가 등록 절차를 시작함
2. **AMF 인증 처리**: AMF가 UDM 등과 연동해 가입자 인증과 기본 정책 확인을 수행함
3. **SMF 세션 생성**: 세션 요구를 받아 적절한 데이터 경로와 정책을 정함
4. **UPF 경로 선택**: 서비스 위치와 지연 요구에 맞는 UPF를 선택해 사용자면을 구성함
5. **데이터 세션 개통**: 제어면과 사용자면이 연결되면 실제 애플리케이션 데이터가 흐르기 시작함

## Ⅵ. 실무 적용 및 유의점

1. 특화망이나 MEC 연동 환경에서는 사용자 데이터 경로를 짧게 만들기 위해 UPF를 현장 가까이에 분산 배치하되 중앙 제어부와의 장애 분리를 함께 설계하고 종단 간 지연, 세션 복구 시간, 로컬 브레이크아웃 성공률로 효과를 확인함
2. SBA는 NF가 API로 촘촘히 연결되므로 내부망이라고 해도 무조건 신뢰하면 안 되며 NF 간 mTLS, 서비스 인증, 호출량 제어를 적용하고 NRF 등록 상태, API 오류율, 인증 실패율로 운영 건전성을 확인함

## Ⅶ. 결론

5G 코어 SBA의 본질은 통신 코어를 API 기반의 유연한 소프트웨어 구조로 바꾸는 데 있으므로, 성능 향상만큼 서비스 발견과 API 보안 운영이 중요함.
