## 미리 알고가기

- QoS는 네트워크가 모든 패킷을 똑같이 다루지 않고 서비스 중요도에 따라 지연, 손실, 대역폭을 다르게 관리하는 방식임
- DSCP는 패킷에 우선순위나 서비스 등급을 표시하는 값임
- RSVP는 흐름별 자원을 미리 예약하기 위한 신호 프로토콜임
- 지터는 패킷 도착 간격이 흔들리는 정도로 음성과 영상 품질에 큰 영향을 줌

## Ⅰ. 개요

- **정의/개념**: QoS는 트래픽을 분류하고 우선순위를 매겨 지연과 지터와 손실을 통제하는 품질 관리 체계이며, IntServ와 DiffServ는 이를 구현하는 대표 방식임
- **배경/필요성**: 음성, 제어, 일반 데이터는 혼잡에 대한 민감도가 서로 달라서 같은 큐에 몰아넣으면 실시간 서비스부터 품질이 무너지므로 차등 처리 기준이 필요함

## Ⅱ. 특징

- 패킷을 분류한 뒤 표시와 큐잉과 스케줄링으로 처리 우선순위를 나눔
- 같은 QoS라도 흐름별 보장과 등급별 우선순위처럼 구현 방식이 다를 수 있음
- 종단 간 품질은 한 장비의 설정만으로 보장되지 않고 경로 전체 정책 일관성이 중요함
- 품질 보장은 항상 자원 효율과 단순성 사이의 균형 위에서 설계됨

## Ⅲ. 종류 및 비교

| 판단 기준 | IntServ | DiffServ |
|:---|:---|:---|
| 자원 관리 단위 | 개별 흐름마다 자원을 예약함 | 여러 흐름을 등급별 클래스로 묶어 처리함 |
| 제어 방식 | RSVP 같은 신호 절차가 필요함 | 패킷의 DSCP 값을 보고 각 홉이 우선 처리함 |
| 확장성 | 흐름 수가 많아지면 상태 관리 부담이 커짐 | 대규모 망에서도 비교적 단순하게 운영 가능함 |
| 적합한 환경 | 폐쇄망이나 제한된 실시간 제어망에 맞음 | 기업망, 통신망, 데이터센터처럼 큰 환경에 맞음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분류기 | 애플리케이션 종류나 주소나 포트를 기준으로 트래픽을 나눔 |
| 마커 | 패킷에 DSCP 같은 서비스 등급 정보를 표시함 |
| 큐와 스케줄러 | 우선순위 큐나 가중치 기반 큐를 이용해 전송 순서를 조정함 |
| 셰이핑·폴리싱 | 계약 속도와 버스트를 넘는 트래픽을 완화하거나 제한함 |
| 측정 체계 | 지연과 지터와 손실을 수집해 정책 효과를 검증함 |

```text
+-----------+    +-----------+    +-----------+    +-----------+
| 트래픽 분류  | -> | 등급 표시    | -> | 큐잉·스케줄링 | -> | 품질 측정    |
+-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 요구사항 정의   | -> | 트래픽 분류    | -> | 표시·예약 적용 | -> | 큐잉·전송      | -> | 지표 검증      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **요구사항 정의**: 음성, 영상, 제어, 일반 데이터의 우선순위를 정함
2. **트래픽 분류**: 주소, 포트, 응용 종류를 기준으로 흐름을 구분함
3. **표시나 예약 적용**: DiffServ는 등급을 표시하고 IntServ는 흐름별 자원을 예약함
4. **큐잉과 전송**: 장비가 등급에 따라 큐와 스케줄을 다르게 적용함
5. **지표 검증**: 지연과 지터와 손실이 목표 안에 들어오는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 음성이나 영상이 섞인 기업망은 DiffServ가 운영하기 쉽지만 구간마다 DSCP 해석이 다르면 기대한 우선순위가 깨지므로 경계 장비부터 정책을 통일하고 큐 길이와 지터와 패킷 손실로 확인해야 함
2. 공장 제어망처럼 흐름 수는 적고 지연 상한이 엄격한 환경은 IntServ 계열 사고가 유효하지만 예약 상태가 많아지면 관리가 무거워지므로 대상 흐름을 좁혀 쓰고 예약 성공률과 응답 지연으로 확인해야 함

## Ⅶ. 결론

QoS 설계의 핵심은 모든 트래픽을 우선 처리하는 데 있지 않고 어떤 흐름을 어느 수준까지 보장할지 정한 뒤 그에 맞는 DiffServ나 IntServ 방식을 고르는 데 있음
