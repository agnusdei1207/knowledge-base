## Ⅰ. 개요
- **정의**: 128비트 주소 체계를 사용하는 차세대 인터넷 프로토콜
- **배경/필요성**: IPv4(006 참조)의 약 43억 개 주소가 고갈되어 대규모 주소 공간 확보가 필요함
- **비유**: 전화번호 자릿수를 8자리에서 16자리로 확장하여 번호 부족을 해소하는 것과 동일함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IPv4 대비 개선점과 전환 기술 이해 | 128비트, 헤더 간소화, 자동 구성, 전환 기술 3종 | 듀얼스택·터널링·변환 혼동 |

> 요약: 128비트 주소로 고갈 문제를 해결하고 헤더 간소화·자동 구성을 제공하는 차세대 IP임

## Ⅱ. 구성요소
```text
IPv6 Address (128 bit, 16진수 8그룹)
2001:0db8:85a3:0000:0000:8a2e:0370:7334

IPv6 Header (40 bytes, fixed)
+----------+--------+---------+----------+
| Version  | Traffic| Flow    | Payload  |
| (4bit)   | Class  | Label   | Length   |
+----------+--------+---------+----------+
| Next Hdr | Hop Limit | Src Addr (128b) |
+-----------+-----------+-----------------+
|           Dst Addr (128 bit)            |
+-----------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 128비트 주소 | 약 3.4x10^38개 주소 제공 | 무한에 가까운 전화번호 |
| 고정 헤더(40B) | 옵션 필드 제거로 라우터 처리 속도 향상 | 표준화된 봉투 규격 |
| Extension Header | 필요 시 체인 방식으로 옵션 추가 | 봉투에 추가 라벨 부착 |
| SLAAC | 라우터 광고 기반 호스트 자동 주소 설정 | 자동 좌석 배정 |

> 요약: 128비트 주소, 고정 헤더, 확장 헤더, 자동 구성이 핵심 구성요소임

## Ⅲ. 절차
```text
[전환 전략 수립] --> [듀얼스택 구성] --> [터널링 적용] --> [완전 전환]
```
- 1단계: 기존 IPv4 인프라 현황 분석 및 IPv6 전환 로드맵 수립
- 2단계: 듀얼스택 구성으로 IPv4/IPv6 동시 운용 환경 구축
- 3단계: IPv4 전용 구간에 6to4, ISATAP 등 터널링 기술 적용
- 4단계: IPv4 의존도 제거 후 네이티브 IPv6 환경으로 완전 전환

> 요약: 현황 분석→듀얼스택→터널링→완전 전환의 단계적 마이그레이션을 수행함

## Ⅳ. 문제점
- 전환 비용: 기존 장비·애플리케이션의 IPv6 호환성 확보에 교체·업그레이드 비용 발생
- 운용 복잡성: 듀얼스택 병행 운용 시 이중 관리 부담 — 보안 정책·모니터링 이중화 필요
- 생태계 미성숙: 일부 ISP·서비스의 IPv6 미지원으로 완전 전환이 지연됨

> 요약: 전환 비용, 이중 운용 복잡성, 생태계 미성숙이 IPv6 확산의 장벽임

## Ⅴ. 개선방안
1. 단기: 정부·공공기관 IPv6 의무 적용으로 전환 비용 분산 및 선도 사례 확보
2. 중기: NAT64/DNS64 게이트웨이 구축으로 듀얼스택 없이 IPv4 서비스 접근 지원
3. 장기: IPv6-only 네트워크 설계 표준화로 이중 관리 부담 해소

> 요약: 공공 선도, 변환 게이트웨이, IPv6-only 표준화로 단계적 전환을 추진함

## Ⅵ. 전망
- 발전 방향: 5G·IoT 확산으로 대규모 주소 수요가 IPv6 채택을 가속화 중
- 기술사적 판단: IPv6는 미래 네트워크 인프라의 기본 전제로 전환은 불가피함
- 기술사 제언: IPv4/IPv6 공존 기간 보안 취약점 분석과 전환 전략 수립 역량이 핵심임
