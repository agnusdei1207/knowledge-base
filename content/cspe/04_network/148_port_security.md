# 📖 【암기용】 개념 완전 이해

> 목적: 포트 보안을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 네트워크 스위치의 구멍(포트)마다 "너만 들어와"라고 특정 기기(MAC 주소)를 지정해두고, 다른 기기가 꽂히면 즉시 차단하는 기술
- **왜 필요한가**: 사무실의 빈 랜선에 아무나 자기 노트북을 꽂아 내부 데이터를 훔쳐 가는 것을 막기 위함이다. 또는 허락되지 않은 허브를 연결해서 포트 하나를 수십 명이 나눠 쓰는 '포트 공유'를 방지한다.
- **핵심 직관**: 주차장의 전용 구역(포트)에 내 차 번호(MAC)를 등록해두고, 다른 차가 주차하면 차단기(스위치)가 내려가거나 경보를 울리는 시스템과 같다.

## 깊이 이해
- **배경·문제의식**: 물리적 접근이 가능한 장소(회의실, 로비)의 네트워크 포트는 보안의 가장 약한 고리다. 공격자는 여기에 자신의 기기를 연결해 ARP 스푸핑이나 스니핑 공격을 시도할 수 있다.
- **작동 원리**:
  - **MAC 주소 학습**: 포트에 연결된 기기의 MAC 주소를 기억한다.
  - **최대 개수 제한**: 한 포트에 연결 가능한 MAC 주소 개수를 설정한다. (보통 1개)
  - **위반 대응 (Violation)**: 허락되지 않은 기기가 연결되었을 때 어떻게 할지 결정한다.
    - **Shutdown**: 포트를 아예 꺼버린다. (관리자가 다시 켜야 함)
    - **Restrict**: 패킷은 버리고 보안 위반 로그를 남긴다.
    - **Protect**: 로그 없이 패킷만 조용히 버린다.
- **비유**: 지정석 식당에서 내 자리에 다른 사람이 앉으면, 주인이 그 테이블을 치워버리거나(Shutdown), "저기요"라고 주의를 주며 음식을 안 주는(Restrict) 상황이다.
- **구체 예시**: "회의실 스위치 1번 포트는 MAC 주소 'AA:BB:CC'만 허용하고, 다른 게 꽂히면 포트를 셧다운하라"라고 설정하는 것이다.
- **흔한 오해·주의점**: "MAC 주소는 가짜로 바꿀 수(Spoofing) 있지 않나?" 맞다. 그래서 포트 보안은 '물리적인 무단 연결'을 막는 1차 방어선이며, 더 강력한 보안을 위해서는 802.1X 같은 인증 기술과 병행해야 한다.

## 연결 개념
- **Sticky MAC**: 한 번 연결된 MAC 주소를 설정 파일에 자동으로 저장하여 재부팅 후에도 기억하게 하는 기술
- **MAC Flooding Attack**: 수만 개의 가짜 MAC을 보내 스위치를 먹통으로 만드는 공격 (포트 보안으로 방어 가능)
- **Error-disable**: 위반으로 인해 포트가 강제로 꺼진 상태

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 포트 보안의 MAC 학습 방식(Static, Dynamic, Sticky)과 보안 위반 시의 처리 모드(Shutdown, Restrict, Protect)의 차이점을 기술적 메커니즘과 관리 편의성 관점에서 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 포트 보안은 L2 스위치의 물리적 인터페이스별로 접속 가능한 단말의 MAC 주소와 개수를 제한하여 비인가 접근을 원천 차단하는 계층 2 보안 기술이다.
> 2. **가치**: MAC Flooding 공격 방어, 인가되지 않은 비인가 공유기(허브) 연결 차단 및 단말 가시성 확보를 통한 내부망 보안을 강화한다.
> 3. **판단 포인트**: 운영 환경의 유연성을 위해 Sticky MAC 기능을 활용하고, 장애 감지 및 복구 정책(Error-disable recovery)을 사전에 정의해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| L2 스위치 포트 수준의 보안 관리 역량 확인 | MAC 주소 제한, Violation Mode (3종) | 모드별 차이점(Log 생성 여부 등) 기술 누락 |
| 내부망 물리 보안 위협 대응 파악 | MAC Flooding 대응, Sticky MAC 개념 | 단순히 "포트를 막는다"는 식의 결과만 설명 |
| 장애 복구 및 관리 효율성 고려 여부 확인 | Error-disable 상태, 자동 복구(Recovery) 설정 | 보안 위반 후 관리자의 사후 조치 절차 간과 |

> 요약: MAC 주소 기반의 물리적 통제 수단으로서의 명확한 동작 모드와 관리적 편의 기능을 부각함.

## Ⅰ. 개요 및 필요성

- 정의: 스위치 포트에 접근 가능한 단말의 MAC 주소를 지정하거나 개수를 제한하여 L2 수준에서 비인가 접속을 차단하는 보안 기술
- 배경: 물리적으로 노출된 네트워크 포트를 통한 내부망 침입, MAC Flooding 공격으로 인한 스위치 기능 마비 위험
- 필요성: 인가된 단말만 접속 허용(자산 관리), 비인가 허브/공유기 무단 연결 방지, 내부 보안 정책 강제화

---

## Ⅱ. 구조 및 구성요소

```text
[포트 보안 동작 구조]
User Device (MAC: A) -> [Switch Port] -> [MAC Table / Secure MAC List] -> [Packet Forwarding]
                          |
Invalid Device (MAC: B) -> [Switch Port] -> [MAC Table / Secure MAC List] -> [Violation Action!!]
```

| 구성요소 | 역할 및 특징 | 핵심 설정 |
|:---|:---|:---|
| Secure MAC | 해당 포트에서 통신이 허용된 합법적인 MAC 주소 리스트 | Static, Dynamic, Sticky |
| Max MAC Count | 포트당 허용 가능한 최대 MAC 주소 개수 (기본값 1) | switchport port-security maximum |
| Violation Mode | 위반 발생 시 포트의 상태 변경 및 경보 수준 결정 | Shutdown, Restrict, Protect |
| MAC Address Table | 수신 패킷의 소스 MAC과 포트를 매핑하는 학습 테이블 | CAM Table 연동 |

> 요약: 포트에 설정된 임계치(최대 개수)와 허용 리스트(Secure MAC)를 기준으로 패킷 통과 여부를 결정함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[포트 보안 위반 처리 흐름]
Packet Arrival -> [Port Security Enabled?] -> No -> Normal Forwarding
      | Yes
[Source MAC in Secure List?] -> Yes -> Forwarding & Update Timer
      | No
[Max MAC Count Reached?] -> No -> Add to Secure List & Forwarding
      | Yes
[Security Violation Action!!] -> Mode: Shutdown (Error-disable) / Restrict (Log) / Protect (Drop)
```

| 단계 | 처리 내용 | 확인 지표 |
|:---:|:---|:---|
| 1 | 포트로 수신된 프레임의 소스 MAC 주소 추출 | L2 Frame Header |
| 2 | 해당 MAC이 기학습된 Secure MAC인지 확인 | Secure MAC Table 조회 |
| 3 | 신규 MAC인 경우, 현재 포트의 학습 개수와 Max 설정값 비교 | Maximum Count 체크 |
| 4 | 임계값 초과 시 설정된 Violation 정책에 따라 즉시 처분 | SNMP Trap, Syslog 생성 |

> 요약: 학습된 MAC이 아니거나 최대 수용량을 초과할 경우 즉각적인 차단 및 관리자 알림을 수행함.

## Ⅳ. 특징

### 1. MAC 학습 방식 비교
| 구분 | Static MAC | Dynamic MAC | Sticky MAC |
|:---|:---|:---|:---|
| 등록 방식 | 관리자가 수동 입력 | 자동 학습 (휘발성) | 자동 학습 후 설정 저장 (비휘발성) |
| 설정 보존 | 재부팅 시 유지 | 재부팅 시 삭제 | **재부팅 시 유지 (Running-config)** |
| 특징 | 최고 보안, 관리 부하 | 관리 편의, 보안 낮음 | **보안과 편의성 절충형** |

### 2. 위반 모드(Violation Mode) 상세
| 모드 | 패킷 차단 | 로그 생성 | SNMP Trap | 포트 상태 |
|:---|:---:|:---:|:---:|:---:|
| **Shutdown** | Yes | Yes | Yes | **Error-disable (꺼짐)** |
| **Restrict** | Yes | Yes | Yes | Up (켜짐 유지) |
| **Protect** | Yes | No | No | Up (켜짐 유지) |

> 요약: 가장 일반적인 운영 방식은 보안 위반을 명확히 인지할 수 있는 'Shutdown' 또는 'Restrict' 모드임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 포트 보안 (Port Security) | 802.1X 인증 | 선택 기준 |
|:---|:---|:---|:---|
| 인증 주체 | MAC 주소 (하드웨어 식별자) | 사용자 계정/인증서 (사람) | 보안 신뢰 수준 |
| 우회 가능성 | MAC Spoofing으로 우회 가능 | 우회 매우 어려움 | 위협 모델 |
| 구축 비용 | 낮음 (대부분 스위치 지원) | 보통 (RADIUS 서버 필요) | 예산 및 복잡도 |

> 요약: 간단한 단말 제한은 포트 보안으로, 정밀한 사용자 통제는 802.1X로 구현함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과도한 포트 꺼짐 | 정상 사용자의 기기 교체 등 | Errdisable Recovery 자동 복구 설정 | 포트 복구 시간 (초) |
| MAC Spoofing | 공격자가 허용된 MAC으로 위조 | IP Source Guard, DHCP Snooping 병행 | 비인가 IP 차단 건수 |
| 대규모 배포 부하 | 수백 대 스위치 설정 관리 | 자동화 도구(Ansible) 또는 Sticky MAC 활용 | 설정 완료 시간 |

> 요약: 운영 효율성을 위해 Sticky MAC과 Error-disable 자동 복구 기능을 적절히 조합해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 보안 위반 탐지율 | 비인가 단말 접속 시 100% 탐지 | 모의 접속 테스트 |
| 설정 준수율 | 전수 포트 보안 설정 여부 | 스위치 Config 전수 검사 |
| 알림 지연 시간 | 위반 발생 후 5초 이내 NMS 도달 | SNMP Trap 수신 로그 |

> 요약: 실제 차단 여부와 관리자에게 전달되는 로그의 신속성을 정기적으로 점검함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **회의실 포트 보안 강화**: Sticky MAC과 Shutdown 모드를 적용하여, 한 번 등록된 회의실 장비 외에 개인 노트북 무단 연결 시 즉시 포트 차단
2. **공공 장소 키오스크 보호**: 포트 보안 Maximum 1 설정을 통해 키오스크 외에 비인가 허브를 연결하여 네트워크를 확장하려는 시도 원천 봉쇄
3. **통합 보안 체계 연동**: 포트 보안 위반 시 발생하는 SNMP Trap을 SIEM/SOAR과 연동하여 보안 관제 팀에서 즉각적인 현장 조치 유도

**결론 (2줄):**
- 기술사 판단: 포트 보안은 내부망 보안의 최소한의 성의이며, 802.1X 도입 전 단계에서 가장 경제적으로 효과를 볼 수 있는 L2 방어선임
- 향후 방향: 단순 MAC 제한을 넘어 단말의 유형(Fingerprinting)까지 분석하여 자동으로 정책을 할당하는 지능형 포트 보안으로 진화할 것임
