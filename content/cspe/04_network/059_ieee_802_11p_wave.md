# 📖 【암기용】 개념 완전 이해

> 목적: IEEE 802.11p와 WAVE를 차량용 Wi-Fi 정도로만 보지 않고, 고속 이동 차량의 직접 통신 표준으로 이해하게 만든다.

## 한눈에
- **개요**: IEEE 802.11p는 차량 환경용 무선 LAN 물리·MAC 표준이고, WAVE는 차량 통신을 위한 상위 프로토콜 체계다.
- **왜 필요한가**: 차량은 고속 이동 중에도 교차로·급정거·도로공사 정보를 수십 ms~100ms 수준으로 교환해야 한다.
- **핵심 직관**: Wi-Fi를 집 안이 아니라 도로 위 고속 차량이 짧은 안전 메시지를 주고받도록 조정한 표준이다.

## 깊이 이해
- **배경·문제의식**: 일반 Wi-Fi는 AP 연결, 인증, 스캔 절차가 차량 안전 메시지에 맞지 않는다. IEEE 802.11p는 OCB(Outside the Context of a BSS)로 AP 연결 없이 통신한다.
- **작동 원리**: 5.9GHz 대역에서 10MHz 채널을 사용하고, OFDM과 CSMA/CA 기반으로 OBU와 RSU가 안전 메시지를 전송한다. WAVE는 IEEE 1609 계열로 네트워킹, 보안, 멀티채널 동작을 정의한다.
- **비유**: 도로 위 차량들이 와이파이 공유기에 접속하지 않고, 정해진 공용 무전 채널에서 짧은 경고문을 방송하는 방식이다.
- **구체 예시**: RSU는 신호 잔여 시간(SPaT)과 교차로 지도(MAP)를 방송하고, 차량 OBU는 위치·속도 기반 BSM을 주변 차량에 전송한다.
- **흔한 오해·주의점**: 802.11p는 WAVE 전체가 아니다. 802.11p는 PHY/MAC이고, WAVE는 IEEE 1609 보안·네트워킹까지 포함한다.

## 연결 개념
- DSRC — IEEE 802.11p/WAVE 기반 차량 통신 서비스 명칭
- RSU/OBU — 도로변·차량 탑재 통신 장치
- C-V2X — 3GPP 계열 대안 차량 통신 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: IEEE 802.11p WAVE 답안에서 PHY/MAC과 WAVE 상위 계층, 차량 안전 메시지 흐름을 분리해 쓴다.
> 핵심: 출제자는 DSRC 기반 기술의 구조와 C-V2X 대비 판단 포인트를 확인한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IEEE 802.11p는 차량 고속 이동 환경을 위한 5.9GHz 기반 PHY/MAC이고, WAVE는 IEEE 1609 계열 상위 차량 통신 체계다.
> 2. **가치**: OCB 모드, 10MHz 채널, RSU/OBU 직접 통신으로 AP 접속 없이 안전 메시지를 교환한다.
> 3. **판단 포인트**: CSMA/CA 혼잡, 멀티채널, WAVE 보안, RSU 배치, C-V2X 전환 가능성을 함께 검토해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 차량용 직접 통신 표준 체계
- 배경: 일반 Wi-Fi 연결 절차는 고속 이동 차량의 안전 메시지 주기에 맞지 않음
- 필요성: OCB, 10MHz 채널, WAVE 스택으로 RSU와 OBU 간 저지연 메시지를 전송

---

## Ⅱ. 구조 및 구성요소

```text
Vehicle OBU -> IEEE 802.11p PHY/MAC -> Neighbor OBU
Vehicle OBU -> IEEE 802.11p -> RSU -> Traffic Center
WAVE Stack -> IEEE 1609 Networking/Security -> Safety Application
PKI -> Message Signing -> Verification -> Warning
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| IEEE 802.11p | 차량용 PHY/MAC | 5.9GHz, 10MHz 채널, OCB |
| WAVE/IEEE 1609 | 네트워크·보안·멀티채널 | WSMP, 보안 서비스 |
| OBU | 차량 탑재 장치 | BSM 송수신 |
| RSU | 도로변 장치 | SPaT, MAP, 경고 방송 |
| Safety App | 충돌·신호·공사 경고 | 100ms 이하 지연 목표 |

> 요약: 802.11p는 무선 접속 계층, WAVE는 차량 안전 서비스를 위한 상위 통신·보안 체계다.

---

## Ⅲ. 동작원리 및 흐름도

```text
차량 상태 수집 -> BSM 생성 -> WAVE 보안 서명
-> 802.11p OCB 전송 -> OBU/RSU 수신
-> 서명 검증 -> 위험 판단
-> 운전자 경고 또는 제어 연계
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 위치·속도·가속도 데이터 수집 | GNSS 오차, timestamp |
| 2 | WAVE 메시지 생성·서명 | certificate validity |
| 3 | 802.11p CSMA/CA로 채널 접속 | channel busy ratio |
| 4 | 주변 OBU/RSU가 메시지 수신 | packet delivery ratio |
| 5 | 안전 애플리케이션 경고 판단 | latency 100ms 이하 목표 |

> 요약: WAVE 메시지는 보안 처리 후 802.11p 직접 통신으로 전송되고 수신 측에서 즉시 위험 판단에 쓰인다.

| 운영/위험 | 셀룰러망 연동 | 독립 직접 통신 | 혼잡·상호운용 시험 필요 |

> 요약: 802.11p WAVE는 기존 DSRC 인프라와 독립 직접 통신 요구가 큰 구간에서 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|

| 보안 위협 | 위조 BSM·재전송 | WAVE PKI, timestamp, CRL | signature failure rate |

> 요약: WAVE 운영은 혼잡 제어, 메시지 인증, C-V2X 혼재 대응을 동시에 관리해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |

| 지연 | 안전 메시지 100ms 이하 목표 | packet timestamp |
| 전달률 | PDR 90% 이상 목표 | OBU/RSU capture |
| 보안 | 인증서 검증 실패율 기준치 이하 | PKI log, CRL audit |

> 요약: 802.11p WAVE 검증은 지연, 전달률, 보안 검증 로그로 수행한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 교차로·고속도로 구간에 RSU 위치를 설계하고 OBU 메시지 수신률을 차량 속도·밀도별로 시험함
2. WAVE PKI, 인증서 폐기, BSM/SPaT/MAP 메시지 검증 절차를 안전 애플리케이션과 연계함
3. C-V2X 전환 가능 구간은 듀얼모드 RSU/OBU와 상호운용 시험을 포함해 단계적 전환 계획을 수립함

**결론 (2줄):**
- 기술사 판단: 기존 DSRC 인프라와 직접 통신 연속성이 중요하면 802.11p WAVE를 유지·보완하고, 5G 연계 서비스는 C-V2X를 병행 검토함
- 향후 방향: 차량 통신은 WAVE 단독보다 DSRC/C-V2X 혼재와 PKI 공통 신뢰체계 중심으로 운영됨
