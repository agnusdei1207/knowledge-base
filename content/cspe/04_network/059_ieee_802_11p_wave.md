## 미리 알고가기

- WAVE는 차량 환경용 무선 통신 체계로 IEEE 802.11p와 1609 계열 표준을 함께 가리킴
- OCB는 일반 Wi-Fi처럼 접속 절차를 길게 밟지 않고 바로 통신하는 운용 모드임
- WSMP는 차량 안전 메시지 전달에 맞춘 경량 메시지 프로토콜임
- CCH는 안전 메시지 중심의 제어 채널이고 SCH는 일반 서비스 채널임
- RSU는 도로변에서 차량과 통신하는 노변 장치임

## Ⅰ. 개요

- **정의/개념**: IEEE 802.11p WAVE는 고속 이동 차량 환경에서 짧은 안전 메시지를 빠르게 주고받기 위해 일반 Wi-Fi를 차량용으로 조정한 무선 통신 체계임
- **배경/필요성**: 일반 Wi-Fi는 접속 절차와 이동성 대응 한계 때문에 차량이 짧은 시간 스쳐 지나가는 환경에 맞지 않으므로, 연결 수립 시간을 줄이고 고속 이동에 맞춘 차량 전용 무선 방식이 필요했음

## Ⅱ. 특징

- OCB 모드로 복잡한 연결 절차 없이 즉시 메시지를 전송할 수 있음
- 짧은 안전 메시지 전달에 초점을 맞춰 지연시간을 줄이도록 설계됨
- 제어 채널과 서비스 채널을 분리해 긴급 메시지를 우선 처리함
- 직접 통신 구조에 강점이 있지만 혼잡 환경에서는 채널 경쟁 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 Wi-Fi | IEEE 802.11p WAVE |
|:---|:---|:---|
| 설계 환경 | 정지 또는 저이동 환경의 데이터 접속에 적합함 | 고속 이동 차량 간 안전 메시지 전달에 적합함 |
| 접속 절차 | 탐색, 인증, 연결 절차를 거친 뒤 통신함 | OCB 모드로 빠르게 직접 송신함 |
| 메시지 성격 | 일반 데이터 전송이 중심임 | 짧고 긴급한 차량 안전 메시지가 중심임 |
| 채널 운영 | 일반 무선 LAN 채널 운영을 따름 | CCH와 SCH를 나눠 안전 메시지 우선순위를 보장함 |
| 한계 지점 | 차량 환경 최적화가 약함 | 혼잡 구간에서는 경쟁 기반 채널 접근 한계가 드러날 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 차량 OBU | 차량 상태를 수집하고 주변 차량과 RSU로 메시지를 송수신하는 단말임 |
| RSU | 교차로와 도로변에서 차량 메시지를 수신하고 인프라 정보를 전달함 |
| OCB 운용 모드 | 일반 AP 연결 절차를 생략하고 통신 범위에 들어오면 바로 메시지를 보내게 함 |
| WSMP | 안전 메시지를 짧고 단순하게 전달하기 위한 상위 프로토콜임 |
| 멀티 채널 구조 | 제어 채널과 서비스 채널을 분리해 긴급 메시지를 우선 처리하게 함 |

```text
+-------+     +------------+     +-------+     +-----------+
| 차량 A | --> | OCB 직접 통신  | --> | 차량 B | --> | RSU·신호기 |
+-------+     +------------+     +-------+     +-----------+
             WSMP와 채널 분리로 안전 메시지 우선 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 통신 구간 진입 | --> | OCB 즉시 송신 | --> | 제어 채널 수신 | --> | 서비스 여부 판단 | --> | 경고·서비스 반영 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **통신 구간 진입**: 차량이 RSU나 주변 차량의 통신 범위 안으로 들어옴
2. **OCB 즉시 송신**: 별도 연결 수립 없이 자신의 위치와 속도와 이벤트를 바로 보냄
3. **제어 채널 수신**: 수신 측 차량이나 RSU가 긴급 안전 메시지를 우선적으로 받음
4. **서비스 여부 판단**: 메시지 성격에 따라 안전 경고인지 일반 서비스 정보인지 구분함
5. **경고·서비스 반영**: 차량 계기판 경고나 신호 제어 같은 동작으로 반영함

## Ⅵ. 실무 적용 및 유의점

1. 기존 C-ITS 시험망이나 교차로 안전 서비스에서는 802.11p WAVE 자산을 계속 활용할 수 있지만 교통량이 높은 구간에서는 채널 경쟁으로 성능이 흔들릴 수 있으므로 패킷 전달률, 채널 점유율, 경고 지연으로 운영 한계를 확인함
2. 다른 V2X 체계로 전환하는 환경에서는 기존 RSU와 단말의 수명 주기를 고려한 단계적 마이그레이션이 필요하므로 혼용 구간 호환성 시험, 주파수 간섭 여부, 현장 장비 교체 비용으로 전환 계획을 검증함

## Ⅶ. 결론

IEEE 802.11p WAVE는 차량 통신의 출발점을 만든 직접 통신 체계이지만, 설계 판단에서는 혼잡 구간 성능과 장기 전환 경로를 함께 봐야 함.
