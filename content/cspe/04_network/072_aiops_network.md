## Ⅰ. 개요
- **정의**: AI/ML을 활용하여 네트워크 운영의 모니터링·분석·자동화를 수행하는 기술임
- **배경/필요성**: 네트워크 규모와 복잡도 증가로 수동 운영의 한계가 발생하여 지능형 자동화가 필요함
- **비유**: 숙련된 관제사가 패턴을 보고 판단하는 과정을 AI가 대신하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 기반 네트워크 운영 자동화 원리 | 이상 탐지-근본 원인 분석-자동 조치 흐름 | 단순 모니터링 도구와 AIOps의 차이 명시 필요 |

> 요약: AI/ML 기반으로 네트워크 이상 탐지·분석·자동 대응을 수행하는 지능형 운영 체계임

## Ⅱ. 구성요소
```text
Network Devices --> Data Lake --> ML Engine --> Action Engine --> Operator
     |                |              |               |
  Log/Metric      Normalize      Anomaly         Remediate
  Collection      & Correlate    Detection        / Alert
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Data Lake | 로그·메트릭·이벤트를 수집·정규화·상관분석하는 저장소임 | 병원의 종합 검진 기록부 |
| ML Engine | 수집 데이터에서 이상 패턴 탐지·근본 원인을 분석함 | 의사가 검진 결과로 진단하는 과정 |
| Action Engine | 분석 결과에 따라 자동 복구 또는 운영자 알림을 실행함 | 처방전을 발행하는 단계 |

> 요약: 데이터 수집-ML 분석-자동 조치 3계층으로 운영 자동화를 구현함

## Ⅲ. 절차
```text
Step1 Collect --> Step2 Analyze --> Step3 Decide --> Step4 Act
```
- 1단계: 네트워크 장비에서 로그·메트릭·플로우 데이터를 실시간 수집함
- 2단계: ML 모델이 베이스라인 대비 이상 패턴을 탐지하고 근본 원인을 추론함
- 3단계: 탐지 결과의 신뢰도·영향도를 평가하여 자동 조치 여부를 결정함
- 4단계: 자동 복구 스크립트 실행 또는 운영자에게 조치 권고를 전달함

> 요약: 수집-분석-결정-조치 루프로 네트워크 장애 대응을 자동화함

## Ⅳ. 문제점
- 오탐(False Positive): ML 모델 정확도 부족으로 정상 트래픽을 이상으로 판정하여 불필요한 알림이 발생함
- 학습 데이터 부족: 신규 장애 유형에 대한 레이블 데이터가 부족하여 탐지율이 저하됨
- 자동 조치 신뢰성: 잘못된 자동 복구가 2차 장애를 유발할 위험이 존재함

> 요약: 오탐, 학습 데이터 부족, 자동 조치 신뢰성이 핵심 과제임

## Ⅴ. 개선방안
1. 단기: 피드백 루프를 통해 오탐 사례를 재학습하여 모델 정밀도를 향상함
2. 중기: 시뮬레이션 환경에서 합성 장애 데이터를 생성하여 학습 데이터를 보강함
3. 장기: 자동 조치 전 시뮬레이션 검증(071 참조) 단계를 추가하여 2차 장애를 방지함

> 요약: 재학습, 합성 데이터, 사전 검증으로 AIOps 신뢰도를 확보함

## Ⅵ. 전망
- 발전 방향: LLM 기반 자연어 인터페이스로 운영자가 의도를 직접 입력하는 방식으로 진화함
- 기술사적 판단: 네트워크 자율운영(Autonomous Network) 실현의 핵심 기반 기술임
- 기술사 제언: 자동 조치 범위와 사람 승인 경계에 대한 거버넌스 체계 수립이 필요함
