# 📖 【암기용】 개념 완전 이해

> 목적: NAC를 단순 접속 차단 장비가 아니라 단말 신원, 상태, 정책을 확인한 뒤 네트워크 접근을 허용하는 통제 체계로 이해하게 만든다.

## 한눈에
- **개요**: NAC는 단말이 네트워크에 접속하기 전 신원과 보안 상태를 검사해 접근 권한을 부여하는 체계
- **왜 필요한가**: 사내망에 노트북, 모바일, IoT, 협력사 장비가 섞이면 미등록 단말과 취약 단말이 내부 시스템에 직접 접근할 수 있다.
- **핵심 직관**: 건물 입구에서 출입증, 방문 목적, 보안 검색을 확인한 뒤 출입 구역을 지정하는 절차와 같다.

## 깊이 이해
- **배경·문제의식**: IP 주소와 포트만으로 내부망 접근을 허용하면 분실 단말, 악성코드 감염 단말, 승인되지 않은 IoT가 같은 네트워크에 들어온다.
- **작동 원리**: 스위치/AP가 접속 요청을 감지하고, NAC가 사용자·단말·상태를 확인한 뒤 VLAN, ACL, 격리망, 포털 인증 정책을 적용한다.
- **비유**: 회사 출입구에서 사원은 사무실로, 방문자는 회의실로, 출입증 없는 사람은 안내 데스크로 보내는 통제와 유사하다.
- **구체 예시**: 802.1X와 RADIUS를 사용해 임직원 노트북은 업무 VLAN, 미등록 단말은 Quarantine VLAN, 게스트는 인터넷 전용 VLAN으로 배치한다.
- **흔한 오해·주의점**: NAC는 방화벽 대체물이 아니라 접속 시점의 인증·상태 점검·세그먼트 배치를 담당하는 접근 통제 계층이다.

## 연결 개념
- 802.1X EAP - 포트 기반 인증의 표준 흐름
- RADIUS - 인증 결과와 정책 속성을 스위치/AP에 전달
- Zero Trust - 접속 위치가 아니라 신원·상태·정책으로 접근을 결정

# 📝 【답안용】 시험 답안 템플릿

> 목적: NAC 답안은 통제 대상, 인증 흐름, 정책 집행, 운영 지표를 분리해 작성한다.
> 핵심: 출제자는 NAC를 보안 장비명으로 아는지보다 내부망 접속 통제 프로세스를 설계할 수 있는지 확인한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NAC는 사용자·단말·상태 정보를 확인하고 VLAN, ACL, 격리망으로 네트워크 접근 범위를 결정하는 통제 체계이다.
> 2. **가치**: 802.1X, RADIUS, Posture Check, Guest Portal을 조합해 미등록·취약 단말의 내부망 접근을 차단한다.
> 3. **판단 포인트**: 통제 대상, 인증 방식, 정책 집행 위치, 예외 처리, 운영 지표를 분리해야 설계 답안이 성립한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 접근 통제 구조 확인 | Supplicant, Authenticator, RADIUS, Policy Server | NAC를 방화벽 기능으로만 설명 |
| 인증·상태 점검 흐름 확인 | 802.1X, MAB, Captive Portal, Posture Check | 사용자 인증과 단말 상태 점검을 혼합 |
| 운영 지표 판단 확인 | 인증 성공률, 미등록 단말, 격리율, 정책 예외 | 차단 정책만 쓰고 업무 예외 프로세스 누락 |

> 요약: NAC 문제는 누가, 어떤 단말로, 어떤 상태에서, 어느 네트워크까지 접근하는지를 정책 흐름으로 쓰는 것이 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 단말 접속 전 접근 권한을 결정
- 배경: 내부망은 임직원 단말, BYOD, IoT, 협력사 장비가 혼재되어 미등록 단말 유입 위험이 존재함.
- 필요성: 사용자 신원, 단말 등록 상태, 보안 상태를 확인해 업무 VLAN, 게스트망, 격리망으로 분리해야 함.
- 판단 기준: 802.1X 적용률, RADIUS 연동, 예외 단말 목록, 격리 정책, 인증 실패 원인으로 운영 수준을 판단함.

---

## Ⅱ. 구조 및 구성요소

```text
Endpoint -> Switch / AP -> NAC Policy Server -> RADIUS / AD / PKI
                              -> VLAN / ACL / Quarantine / Guest Portal
                              -> SIEM / Log / Report
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Endpoint | 사용자 단말, IoT, 프린터 등 접속 주체 | Supplicant, 인증서, Agent 상태 |
| Authenticator | 스위치 또는 무선 AP에서 접속 제어 | 802.1X, MAB, VLAN assignment |
| NAC Policy Server | 신원·단말·상태 기반 정책 결정 | AD, PKI, EDR, CMDB 연동 |
| Enforcement Policy | VLAN, ACL, 격리, 포털 정책 적용 | RADIUS attribute로 전달 |

> 요약: NAC는 단말 접속 지점에서 정책 서버 판단을 받아 VLAN·ACL·격리 정책을 집행하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
단말 접속 -> 802.1X / MAB / Portal 인증 -> RADIUS 질의
-> 사용자 / 단말 / 상태 확인 -> 정책 결정 -> VLAN / ACL 적용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 단말이 스위치 포트 또는 무선 SSID에 접속 | port event, association log |
| 2 | 802.1X, MAB, Captive Portal 중 정책 방식 선택 | authentication method ratio |
| 3 | NAC가 AD, PKI, CMDB, EDR 정보를 조회 | identity match, posture result |
| 4 | RADIUS가 VLAN, ACL, 세션 타임아웃 속성을 반환 | policy assignment success |
| 5 | 미충족 단말을 격리망 또는 게스트망으로 배치 | quarantine count, exception count |

> 요약: NAC 인증 흐름은 접속 감지, 신원 확인, 단말 상태 확인, 정책 반환, 네트워크 세그먼트 배치 순서로 진행된다.

## Ⅳ. 특징

| 구분 | 기존 내부망 접속 | NAC 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 통제 대상 | IP와 포트 중심 | 사용자, 단말, 상태, 위치 | AD, CMDB, EDR 연동 |
| 인증 방식 | MAC/IP 등록 중심 | 802.1X, EAP-TLS, MAB, Portal | RADIUS, PKI |
| 집행 방식 | 고정 VLAN | 동적 VLAN, ACL, 격리망 | Tunnel-Private-Group-ID |
| 운영 지표 | 장애 티켓 중심 | 인증 성공률, 격리율, 예외율 | NAC dashboard, SIEM |

> 요약: NAC는 내부망 접속을 물리 포트 기준에서 신원·상태·정책 기준으로 바꾸는 접근 제어 체계이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 고정 VLAN과 수동 등록 | NAC 정책 서버와 동적 할당 | 단말 종류와 접속 위치가 많은 조직에 적용 |
| 비용/성능 | 운영자 수작업 | 인증 서버, 스위치 연동, 인증서 운영 | 802.1X 지원 장비 비율로 판단 |
| 운영/위험 | 미등록 단말 탐지 지연 | 접속 시점 정책 집행 | 예외 단말과 장애 대응 절차 필요 |

> 요약: NAC는 장비 호환성, 인증서 운영, 예외 정책을 준비한 뒤 단계 도입해야 업무 중단을 줄일 수 있다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 단말 차단 | 인증서 누락 또는 정책 오분류 | Pilot VLAN, 예외 승인, 단계 배포 | authentication failure rate |
| IoT 인증 불가 | 802.1X supplicant 미지원 | MAB, Profiling, 제한 ACL 적용 | MAB device count |
| 정책 우회 | 미관리 스위치 또는 Rogue AP | 포트 보안, 무선 탐지, 로그 상관분석 | rogue device count |

> 요약: NAC 리스크는 오차단, IoT 예외, 우회 접속으로 나뉘며 예외 정책과 탐지 지표가 필수이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 품질 | 802.1X 성공률과 실패 원인 관리 | RADIUS log, NAC dashboard |
| 통제 품질 | 미등록 단말 격리와 예외 승인 추적 | quarantine report, exception ticket |
| 운영 연계 | SIEM, EDR, CMDB 정보 일치 | log correlation, asset reconciliation |

> 요약: NAC 운영은 인증 성공률, 격리 현황, 자산 정보 일치도를 함께 점검해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 임직원 단말은 EAP-TLS와 PKI 기반 802.1X를 적용하고 인증서 수명주기를 관리함.
2. IoT와 프린터는 MAB와 Profiling으로 식별한 뒤 제한 ACL과 전용 VLAN을 적용함.
3. NAC 로그를 SIEM, CMDB, EDR과 연동해 미등록 단말, 격리 단말, 정책 예외를 주기 점검함.

**결론 (2줄):**
- 기술사 판단: 관리 단말 비율이 높으면 802.1X 중심 NAC를 적용하고, IoT 비중이 높으면 MAB·Profiling·격리 VLAN을 병행함.
- 향후 방향: NAC는 ZTNA, EDR, SASE와 연동되어 접속 시점 통제에서 지속적 접근 검증으로 확장됨.
