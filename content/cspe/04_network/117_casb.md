## 미리 알고가기

- SaaS는 설치 없이 인터넷으로 바로 쓰는 소프트웨어 서비스임
- 섀도 IT는 조직 승인 없이 직원이 임의로 쓰는 클라우드 서비스임
- API 연동 방식은 클라우드 서비스와 직접 연결해 저장 데이터와 설정을 점검하는 방식임
- 프록시 방식은 사용자 트래픽 중간에서 실시간으로 검사하는 방식임

## Ⅰ. 개요

- **정의/개념**: CASB는 사용자와 클라우드 서비스 사이에서 SaaS 사용 현황을 보이게 하고 데이터 이동과 접근 행위를 정책으로 통제하는 보안 중계 계층임
- **배경/필요성**: SaaS 확산으로 데이터가 사내 밖 여러 서비스에 흩어지면서 누가 무엇을 올리고 공유하는지 보이지 않게 됐으므로, 클라우드 사용 가시성과 통제를 묶은 장치가 필요함

## Ⅱ. 특징

- 승인 서비스와 비승인 서비스를 구분해 섀도 IT를 드러낼 수 있음
- 업로드와 다운로드와 공유 같은 행위를 데이터 정책으로 제어할 수 있음
- 프록시와 API 연동을 함께 쓰면 이동 중 데이터와 저장된 데이터를 모두 볼 수 있음
- 클라우드 서비스별 API 범위가 달라 통제 깊이가 균일하지 않을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 프록시 방식 CASB | API 연동 CASB |
|:---|:---|:---|
| 검사 시점 | 사용 중인 트래픽을 실시간으로 검사함 | 저장된 데이터와 설정을 사후 점검함 |
| 통제 범위 | 전송 중 요청 차단과 세션 제어 | 저장 데이터 스캔과 공유 설정 감사 |
| 제약 | 배포 방식과 우회 통로 관리가 중요함 | 서비스 API 범위에 따라 통제 폭이 달라짐 |
| 적합 환경 | 업로드 통제와 실시간 접근 제어에 적합함 | 데이터 분류와 공유 상태 점검에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 | SaaS를 사용하는 주체임 |
| CASB 엔진 | 행위와 데이터를 검사하고 정책을 적용함 |
| 인증 체계 | 사용자 식별과 그룹 정책 연계를 담당함 |
| SaaS 서비스 | 메일, 협업, 저장소 같은 실제 대상임 |
| 정책·분석 기능 | 데이터 유출, 공유, 이상 행위를 점검함 |

```text
+--------+    접속·전송    +-----------+    정책 반영    +-----------+
| 사용자   | -----------> | CASB 엔진    | ------------> | SaaS 서비스 |
+--------+               +-----------+                +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[서비스 발견] -> [사용자 식별] -> [행위·데이터 검사] -> [허용·차단] -> [사후 점검]
```

1. **서비스 발견**: 어떤 SaaS가 사용되는지 먼저 파악함
2. **사용자 식별**: 계정과 그룹과 기기 정보를 연결함
3. **행위·데이터 검사**: 업로드와 공유와 외부 반출을 점검함
4. **허용·차단**: 정책에 따라 허용, 차단, 경고를 적용함
5. **사후 점검**: 저장 데이터와 공유 설정을 다시 검사함

## Ⅵ. 실무 적용 및 유의점

1. 협업 SaaS가 많은 조직은 CASB로 비인가 서비스와 외부 공유를 식별·차단하며, 프록시를 우회한 저장 데이터도 점검하도록 API 연동을 병행하고 비승인 SaaS 발견 건수, 외부 공유 건수, 차단 성공률을 확인함
2. 민감 정보 보호가 목적이라면 파일 분류 정책이 먼저 맞아야 하므로 DLP 기준과 사용자 그룹 정책을 함께 정리하고 정책 오탐 건수와 예외 승인 건수를 계속 봐야 함

## Ⅶ. 결론

CASB의 핵심은 클라우드 사용을 보이게 만드는 데서 끝나지 않고 데이터와 행위를 사용자 기준으로 실제 통제하는 데 있음.
