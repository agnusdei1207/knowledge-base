# 📖 【암기용】 개념 완전 이해

> 목적: CASB를 SaaS 사용 가시성과 데이터 통제를 제공하는 중간 통제 계층으로 이해하게 만든다.

## 한눈에
- **개요**: CASB는 사용자와 클라우드 서비스 사이에서 SaaS 사용, 데이터 이동, 위협 행위를 가시화하고 통제하는 보안 서비스이다.
- **왜 필요한가**: 사용자는 회사 승인 없이도 SaaS를 사용할 수 있고, 파일 공유 링크와 외부 계정 권한으로 데이터가 유출될 수 있다.
- **핵심 직관**: 회사 밖 창고에 문서를 보관하더라도 누가 어떤 문서를 올리고 공유했는지 출입 기록과 반출 검사를 붙이는 방식이다.

## 깊이 이해
- **배경·문제의식**: SaaS는 도입이 쉽지만 관리자 가시성, 데이터 분류, 외부 공유, 계정 탈취 탐지가 서비스별로 흩어진다.
- **작동 원리**: CASB는 API 연동으로 저장된 데이터와 권한을 점검하고, Proxy 방식으로 실시간 업로드·다운로드·공유 행위를 검사한다.
- **비유**: 문서 보관소 관리자와 출입 보안요원이 함께 동작해 저장된 문서 상태와 실시간 반출 행위를 모두 확인하는 구조다.
- **구체 예시**: CASB는 Microsoft 365의 외부 공유 파일을 API로 스캔하고, 사용자가 개인 Gmail로 기밀 파일을 업로드하면 Proxy DLP로 차단한다.
- **흔한 오해·주의점**: CASB는 SaaS 보안만 담당한다. 웹 악성 사이트 차단은 SWG, 사내 앱 접근 제어는 ZTNA가 담당한다.

## 연결 개념
- SSE/SASE - CASB를 SWG, ZTNA, DLP와 통합 제공
- DLP - CASB의 데이터 탐지·차단 정책 핵심
- SaaS 보안 형상관리 - SaaS 설정 오류와 권한 노출 점검

# 📝 【답안용】 시험 답안 템플릿

> 목적: CASB 답안은 API 방식과 Proxy 방식, Shadow IT, DLP, 위협 탐지를 명확히 구분한다.
> 핵심: SaaS 가시성, 데이터 보호, 위협 탐지, 준수 증적을 표와 지표로 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CASB는 클라우드 서비스 사용 행위와 데이터를 중개·분석해 정책을 적용하는 SaaS 보안 통제 계층이다.
> 2. **가치**: Shadow IT 탐지, SaaS 권한 점검, DLP, 계정 탈취 탐지를 API와 Proxy 방식으로 수행한다.
> 3. **판단 포인트**: API는 사후 점검과 저장 데이터 분석, Proxy는 실시간 제어와 업로드 차단에 적합하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 접근 통제 이해 확인 | API CASB, Proxy CASB, DLP, Shadow IT | CASB를 단순 프록시로만 설명 |
| SaaS 데이터 보호 판단 확인 | 외부 공유, 공개 링크, 민감정보 업로드 | 저장 데이터와 실시간 트래픽 구분 누락 |
| 운영 증적 제시 확인 | 사용자, 앱, 파일, 정책, 처리 결과 | "클라우드 보호" 같은 추상 표현 |

> 요약: CASB 문제는 SaaS 사용 가시성과 데이터 통제를 어떤 방식으로 구현하는지 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: SaaS 접근 보안 중개 계층
- 배경: SaaS 사용과 외부 공유가 늘면서 데이터 위치와 권한 상태가 서비스별로 분산됨.
- 필요성: API/Proxy 방식으로 Shadow IT, DLP, 계정 탈취, 규정 위반을 탐지해야 함.
- 판단 기준: 승인 SaaS 수, 외부 공유량, 민감정보 처리 여부, 실시간 차단 필요성을 기준으로 도입함.

---

## Ⅱ. 구조 및 구성요소

```text
User -> CASB Proxy -> SaaS App
SaaS API -> CASB API Scanner -> Data/Permission Analysis
CASB Policy Engine -> DLP/Threat/Compliance -> SIEM/SOAR
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| API Connector | SaaS 저장 데이터, 권한, 로그를 수집 | Microsoft 365, Google Workspace, Salesforce |
| Forward/Reverse Proxy | 실시간 접속과 파일 업로드를 검사 | 관리 단말과 비관리 단말 정책 분리 |
| DLP Engine | 개인정보, 소스코드, 영업비밀을 탐지 | 정규식, EDM, 파일 지문 |
| Threat Analytics | 이상 로그인과 대량 다운로드를 탐지 | UEBA, impossible travel |
| Compliance Report | 규정 위반과 조치 이력을 제공 | 감사 증적, 보존 기간 관리 |

> 요약: CASB는 API로 저장 상태를 점검하고 Proxy로 실시간 행위를 통제한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
SaaS 목록 수집 -> 사용자/앱 위험 평가 -> API 스캔
-> 실시간 Proxy 검사 -> DLP/위협 정책 적용 -> 차단/격리/승인 -> 로그 전송
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 프록시 로그와 IdP 로그로 SaaS 사용 목록을 수집 | 승인·비승인 앱 분류 |
| 2 | API로 파일, 권한, 공유 링크를 분석 | 외부 공유, 공개 링크, 민감정보 |
| 3 | Proxy가 업로드·다운로드·로그인을 실시간 검사 | 사용자, 단말, 위치, 파일 해시 |
| 4 | 정책에 따라 차단·격리·암호화·승인을 수행 | DLP 룰, 위험 점수, 예외 승인 |
| 5 | 결과를 SIEM/SOAR와 티켓으로 전달 | 앱 ID, 사용자 ID, 정책 결과 |

> 요약: CASB는 SaaS 사용을 식별하고 저장 데이터와 실시간 행위에 각각 다른 통제를 적용한다.

## Ⅳ. 특징

| 구분 | 기존 SaaS 사용 | CASB 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 가시성 | 부서별 개별 가입 | Shadow IT 탐지 | 앱 위험 점수, 사용자 수 |
| 데이터 통제 | SaaS 자체 설정 의존 | DLP, 암호화, 격리 | 개인정보 정규식, EDM |
| 권한 관리 | 공개 링크·외부 공유 누락 | API 기반 권한 점검 | 외부 공유 파일 수 |
| 위협 탐지 | 서비스별 로그 분산 | UEBA와 이상 로그인 탐지 | impossible travel, 대량 다운로드 |

> 요약: CASB는 SaaS 사용, 데이터, 권한, 위협 로그를 한곳에서 분석해 정책을 적용한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | API CASB | Proxy CASB | 선택 기준 |
|:---|:---|:---|:---|
| 통제 시점 | 사후 스캔, 저장 상태 분석 | 실시간 접속 제어 | 업로드 차단 필요 여부 |
| 적용 대상 | 승인 SaaS | 승인·비승인 SaaS 일부 | API 지원 여부 |
| 사용자 영향 | 낮음 | 트래픽 경유로 인증서·지연 고려 | 업무 민감도 |
| 주요 지표 | 외부 공유 파일, 민감정보 발견 | 차단 이벤트, 오탐률 | 감사 요구와 실시간성 |

> 요약: 저장 데이터 점검은 API 방식, 실시간 반출 차단은 Proxy 방식을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| API 권한 과다 | CASB 커넥터가 광범위 권한 보유 | 최소 권한, 권한 리뷰 | API 권한 변경 이력 |
| DLP 오탐 | 문서 맥락 미반영 | EDM, 승인 워크플로, 샘플 검토 | 오탐률, 승인 건수 |
| 우회 업로드 | 비관리 단말 또는 개인 네트워크 | Reverse proxy, IdP 조건부 접근 | 비관리 접속 비율 |
| SaaS 미탐 | 신규 앱 사용 미등록 | SWG 로그 연계, 정기 앱 분류 | 신규 Shadow IT 앱 수 |

> 요약: CASB 리스크는 API 권한, DLP 품질, 우회 접속, 미등록 SaaS에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| SaaS 가시성 | 승인·비승인 앱 식별률 95% 이상 | CASB discovery, SWG 로그 |
| 데이터 통제 | 공개 링크 민감 파일 0건 | API 스캔, DLP 리포트 |
| 위협 탐지 | 계정 탈취 MTTD 10분 이하 | UEBA, SIEM 상관분석 |
| 감사 증적 | 사용자·앱·파일·정책 결과 100% 기록 | 로그 필드 매핑 점검 |

> 요약: CASB 성과는 SaaS 식별, 민감 파일 통제, 계정 위협 탐지, 감사 로그 완전성으로 확인한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. Microsoft 365, Google Workspace, Salesforce 같은 주요 SaaS에 API Connector를 등록하고 외부 공유·공개 링크를 스캔함.
2. 비관리 단말과 민감 파일 업로드는 Reverse Proxy와 DLP 정책으로 차단 또는 승인 워크플로에 연결함.
3. CASB 이벤트를 SIEM/SOAR로 전송하고, 대량 다운로드, impossible travel, 민감 파일 외부 공유를 playbook으로 처리함.

**결론 (2줄):**
- 기술사 판단: SaaS 데이터와 외부 공유가 핵심 위험이면 CASB API와 Proxy를 병행 적용함.
- 향후 방향: CASB는 SSE 안에서 SWG, ZTNA, DLP, SSPM과 통합되어 SaaS 보안 운영면으로 확장됨.
