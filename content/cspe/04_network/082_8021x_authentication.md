## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 스위치 포트나 무선 랜 접속 시, 정당한 사용자인지 인증 서버(RADIUS)를 통해 확인 후 포트 통신을 개방하는 L2 계층 접근 통제 표준 |
| **배경/필요성** | 개방된 스위치 포트(LAN)나 무선 공간을 통한 비인가자의 물리적 무단 연결(도둑 접속) 차단 필요 |
| **출제 의도** | Supplicant, Authenticator, Authentication Server로 구성된 3자(3-Tier) 구조와 EAP 확장 인증 메커니즘 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Client  |       |  Switch  |       |  RADIUS  |
| (Supplic)| <---> | (Authen) | <---> | (Server) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Supplicant | 네트워크 접속을 요청하며 EAP 메시지를 처리하는 클라이언트 단말 소프트웨어 | 입장권 제시 고객 |
| Authenticator | 단말과 서버 중간에서 인증 패킷만 통과(EAPOL)시키고 나머지 트래픽은 차단하는 스위치/AP | 검표원 (게이트) |
| Auth Server | 실제 ID/PW 또는 인증서를 검증하고 최종 접속 수락/거절을 지시하는 RADIUS 서버 | 중앙 심사 데이터베이스 |

> 요약: 네트워크 스위치 레벨에서 미인증 트래픽 차단 및 강력한 중앙 인증 기반 L2 포트 보안을 확립함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 접속 요청| -> | 신원 요구| -> | EAP 검증 | -> | 포트 개방|
+----------+    +----------+    +----------+    +----------+
```
1. 접속 요청: 단말(Supplicant)이 스위치에 케이블 연결 시 스위치는 통신 포트를 미인가(Block) 상태로 차단 유지
2. 신원 요구: 스위치(Authenticator)가 단말에게 EAP-Request/Identity 패킷을 보내 신원(ID) 정보 제출 요구
3. EAP 검증: 단말이 제출한 정보(EAP-Response)를 스위치가 RADIUS 서버로 릴레이 전달하고, 서버는 암호화 검증 수행
4. 포트 개방: 인증 성공(EAP-Success) 메시지를 스위치가 수신하면 해당 포트를 정상(Forwarding) 상태로 동적 전환

> 요약: L2 계층에서 EAP 프레임을 교환하고 인증 서버의 승인이 완료되어야만 데이터 포트를 활성화함

## Ⅳ. 문제점
- 프린터나 구형 바코드 스캐너 등 802.1X 기능(Supplicant)이 내장되지 않은 레거시 단말은 인증 구조 수용 절대 불가
- 무선 LAN 로밍(Roaming) 환경에서 AP를 이동할 때마다 전체 802.1X 인증을 재수행하여 실시간 통화(VoIP) 끊김 원인
- 인증 서버(RADIUS) 단일 마비 시 사내 전체 유무선 망 포트 개방 불가 (치명적 단일 장애점 SPOF)

## Ⅴ. 개선방안
- [단기] 구형 기기(프린터 등) 접속을 위해 스위치 포트에 예외적으로 MAC 주소 우회 인증(MAB) 기능 혼합 적용
- [중기] 802.11r(Fast Transition) 및 OKC 기능 활성화로 무선 AP 이동 시 복잡한 EAP 단계를 생략하여 로밍 최적화
- [장기] 다중 RADIUS 서버 이중화(Active-Active) 및 클라우드 기반 인증 시스템(IDaaS) 연동으로 무중단 인증 인프라 구축

## Ⅵ. 전망
- 엔터프라이즈 환경 보안 강화를 위해 유무선 통일된 802.1X 기반의 엄격한 상호 인증이 완전 정착될 것임
