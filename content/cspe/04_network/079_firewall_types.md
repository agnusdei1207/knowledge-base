## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 내외부 네트워크 사이에서 사전 정의된 보안 정책(Rule)을 바탕으로 비인가 트래픽의 통과 여부를 통제하는 보안 게이트웨이 |
| **배경/필요성** | 갈수록 고도화되는 7계층 웹 애플리케이션 공격 방어 및 네트워크 가시성 한계 극복 필요 |
| **출제 의도** | 1세대(패킷 필터), 2세대(상태 기반 SPI), 3세대(WAF 및 NGFW) 방화벽의 구조적 진화 및 차이점 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
| External |       | Firewall |       | Internal |
| (Untrust)| =====>| (Policy) | =====>| (Trust)  |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 패킷 필터링 | IP, Port 헤더 정보만 단순 확인하여 차단하는 1세대 기술 (상태 비저장) | 출입증 겉면 확인 |
| 상태 기반(SPI) | TCP 세션 상태(State) 정보를 추적/저장하여 위조 패킷을 인지하는 2세대 기술 | 출입자 이동 동선 추적 |
| WAF (웹방화벽) | L7 HTTP(S) 페이로드를 심층 분석하여 SQLi, XSS 등 웹 특화 공격을 막는 전용 장비 | 수하물 엑스레이 검사 |

> 요약: 단순 포트 차단을 넘어 연결 문맥(Context)과 콘텐츠(Payload) 중심의 심층 검사로 진화함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 패킷 인입| -> | 세션 확인| -> | 정책 대조| -> | 심층 검사|
+----------+    +----------+    +----------+    +----------+
```
1. 패킷 인입: 외부에서 유입되는 패킷의 L3/L4 헤더(IP 주소, 포트 번호) 기본 추출
2. 세션 확인: (SPI) 기존에 확립된 정상 TCP 세션에 속하는 패킷인지 상태 테이블(State Table) 조회
3. 정책 대조: 관리자가 설정한 접근 제어 목록(ACL) 룰과 매칭하여 허용(Allow)/차단(Drop) 1차 판별
4. 심층 검사: (WAF/NGFW) L7 페이로드까지 뜯어보아 악성코드 시그니처나 비정상 행위 검출 후 최종 허용

> 요약: 기본 헤더 검사부터 세션 상태 추적 및 L7 페이로드 분석까지 다계층 보안 통제 수행

## Ⅳ. 문제점
- [패킷 필터링] 비연결성 특징으로 인해 내부 응답 패킷을 가장한 위조 트래픽(스푸핑)에 속수무책 관통
- [SPI 한계점] L4 정보까지만 확인하므로 포트 80(HTTP)을 타고 들어오는 SQL Injection, XSS 공격 방어 불가
- [WAF 한계점] 트래픽 전체 복호화(SSL) 및 L7 정밀 분석(Regex) 수행에 따른 막대한 CPU 성능 병목 및 처리 지연

## Ⅴ. 개선방안
- [단기] 레거시 패킷 필터 라우터 룰을 폐기하고 전 구간 SPI 방화벽 도입으로 무분별한 포트 오픈 차단
- [중기] 웹 서비스 앞단에 WAF를 전진 배치하고 SSL 오프로드(가속기)를 적용하여 분석 부하 경감 최적화
- [장기] IPS, WAF, 안티바이러스를 통합하고 애플리케이션을 직관적으로 제어하는 차세대 방화벽(NGFW) 전면 재구축

## Ⅵ. 전망
- 클라우드 전환에 따라 하드웨어 장비(Appliance)에서 벗어나 서비스형 보안(SECaaS) 아키텍처로 완전 편입될 것임
