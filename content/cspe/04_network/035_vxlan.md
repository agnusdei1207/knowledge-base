## Ⅰ. 개요
- **정의**: 물리적 IP 네트워크(Underlay) 위에 논리적인 L2 오버레이 네트워크를 구축하기 위해 MAC-in-UDP 등으로 캡슐화하는 기술임.
- **배경/필요성**: 기존 VLAN ID(4096개)의 확장성 한계 극복, 클라우드 데이터센터 내 대규모 테넌트 격리 및 VM 마이그레이션 용이성 확보.
- **출제 의도**: 오버레이 네트워크 개념, VXLAN 캡슐화 구조(VNI, VTEP), 기존 VLAN과의 차별성 및 한계점 파악.

## Ⅱ. 구성요소
```text
+-----------------------------------+
|            Overlay (L2)           |
|         VM A  <----->  VM B       |
+-----------------------------------+
|      VTEP 1             VTEP 2    |
| (En/De-capsulation) (En/De-caps)  |
+-----------------------------------+
|           Underlay (L3)           |
|        Physical IP Network        |
+-----------------------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| VNI | VXLAN Network Identifier로 24비트 체계를 가져 약 1600만 개 테넌트 지원 | 넉넉한 방 번호 |
| VTEP | VXLAN Tunnel End Point, 원본 패킷을 캡슐화/디캡슐화하는 주체(가상/물리스위치) | 택배 포장/해체소 |
| Underlay | 오버레이 터널 트래픽을 라우팅하여 물리적으로 전송하는 기존 IP 네트워크 | 실제 도로망 |
> 요약: VTEP가 원본 L2 패킷에 VNI와 UDP 헤더를 씌워 언더레이 망을 통해 터널링 전송함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 패킷 생성 |-> | 캡슐화(En)  |-> | 터널 전송   |-> | 디캡슐화  |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **패킷 생성**: 출발지 VM이 목적지 VM으로 보낼 원본 이더넷 프레임(L2 패킷)을 생성함.
2. **캡슐화(En)**: 출발지 스위치의 VTEP이 원본 프레임에 24비트 VNI를 추가하고 UDP 포맷으로 캡슐화함.
3. **터널 전송**: 캡슐화된 IP 패킷이 L3 라우팅(언더레이 네트워크)을 통해 목적지 VTEP으로 전달됨.
4. **디캡슐화**: 목적지 VTEP에서 UDP 헤더 및 VNI를 제거하고, 원본 프레임을 목적지 VM으로 전달함.
> 요약: 물리적 위치(L3)와 무관하게 논리적으로 동일한 L2 브로드캐스트 도메인을 유지하는 통신 절차임.

## Ⅳ. 문제점
- **오버헤드 발생**: 캡슐화(약 50 Bytes 헤더 추가)로 인해 MTU 증가 및 네트워크 포워딩 지연 유발.
- **멀티캐스트 의존성**: 초기 VXLAN은 BUM(Broadcast, Unknown unicast, Multicast) 트래픽 처리를 위해 물리 망의 멀티캐스트 설정이 강제됨.
- **가시성 저하**: 언더레이 장비 입장에서는 단순 UDP 트래픽으로 보여, 트래픽 분석 및 디버깅이 어려움.

## Ⅴ. 개선방안
- **성능 최적화**: 서버 NIC에서 캡슐화를 하드웨어 가속 처리하는 VXLAN 오프로드 적용 (단기).
- **컨트롤 플레인 도입**: 멀티캐스트 없이 유니캐스트로 BUM 트래픽을 처리하는 BGP EVPN 도입 (중기).
- **통합 모니터링**: 오버레이-언더레이 매핑 가시성을 제공하는 텔레메트리 및 데이터센터 SDN 연동 (장기).

## Ⅵ. 전망
- VXLAN은 클라우드 및 데이터센터 네트워크에서 L2 확장을 위한 사실상 표준으로 완전히 정착함.
- 향후 Leaf-Spine 라우팅 아키텍처와 BGP EVPN의 결합 구조가 차세대 SDDC(소프트웨어 정의 데이터센터)의 기본 뼈대가 될 것임.
