# 📖 【암기용】 개념 완전 이해

> 목적: 엣지와 포그를 같은 말로 외우지 않고, 처리 위치와 계층 구조의 차이로 이해하게 만든다.

## 한눈에
- **개요**: 엣지는 데이터 발생 지점 가까운 노드에서 처리하고, 포그는 디바이스와 클라우드 사이 중간 계층을 여러 단계로 구성한다.
- **왜 필요한가**: IoT 데이터는 센서 수, 영상 크기, 제어 지연 때문에 모든 데이터를 클라우드로 보내기 어렵다.
- **핵심 직관**: 엣지는 현장 옆 계산대, 포그는 현장-지역-중앙을 잇는 계층형 물류센터다.

## 깊이 이해
- **배경·문제의식**: 클라우드 집중 구조는 네트워크 장애, 대역폭 비용, 데이터 주권, 실시간 제어에서 한계가 있다. 엣지와 포그는 처리 위치를 사용자·장비 쪽으로 내린다.
- **작동 원리**: 엣지는 게이트웨이·기지국·장비 내 컴퓨팅에서 즉시 처리한다. 포그는 엣지 노드, 현장 게이트웨이, 지역 마이크로 데이터센터를 계층화해 필터링·집계·분석을 단계적으로 수행한다.
- **비유**: 엣지는 편의점에서 바로 계산하는 것, 포그는 편의점-지역 물류센터-본사 물류센터가 역할을 나누는 것과 같다.
- **구체 예시**: CCTV 침입 감지는 카메라 NPU에서 1차 탐지, 현장 게이트웨이에서 이벤트 집계, 클라우드에서 장기 학습을 수행하면 포그형 계층 구조다.
- **흔한 오해·주의점**: 포그는 엣지의 반대말이 아니다. 포그는 엣지를 포함한 중간 계층 운영 모델로 보는 것이 정확하다.

## 연결 개념
- MEC — 통신망 엣지에 특화된 엣지 컴퓨팅
- IoT Gateway — 포그 계층의 현장 수집·프로토콜 변환 노드
- Computing Continuum — 클라우드·엣지·디바이스 연속 배치

# 📝 【답안용】 시험 답안 템플릿

> 목적: 엣지와 포그 비교 문제에서 위치, 계층, 지연, 운영 책임을 비교축으로 제시한다.
> 핵심: 출제자는 용어 정의보다 어떤 업무를 어느 계층에 배치할지 판단하는 역량을 본다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 엣지는 데이터 발생 지점 인접 처리, 포그는 디바이스-클라우드 사이 다계층 분산 처리 모델이다.
> 2. **가치**: 지연 민감 처리는 엣지, 지역 집계·정책·프로토콜 변환은 포그, 장기 분석은 클라우드로 역할을 분리한다.
> 3. **판단 포인트**: p95 지연, 데이터량, 장애 격리, 관리 계층 수, 보안 경계를 기준으로 배치해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지·포그 차이 확인 | 위치 중심 엣지, 계층 중심 포그 | 두 용어를 동의어로 처리 |
| IoT 배치 판단 확인 | 센서, 게이트웨이, 지역 DC, 클라우드 역할 | 클라우드와의 연계 누락 |
| 운영 리스크 식별 | 노드 수, 보안 경계, 배포·관측 | 지연 감소만 서술 |

> 요약: 비교형 답안은 처리 위치, 계층 수, 운영 책임, 적용 업무를 표로 분리해야 한다.

## Ⅰ. 개요 및 필요성

엣지와 포그는 클라우드 집중 처리를 분산하는 컴퓨팅 구조다. IoT·영상·제어 데이터는 대역폭과 왕복 지연 때문에 중앙 처리만으로 SLA를 맞추기 어렵다. 엣지는 가까운 처리, 포그는 중간 계층 설계로 데이터 경로를 최적 배치한다.

---

## Ⅱ. 구조 및 구성요소

```text
Device/Sensor -> Edge Node -> Fog Gateway -> Regional Micro DC -> Cloud
      / 즉시 제어       / 집계·필터링       / 분석·정책       / 장기학습
관측/보안 정책 -> 계층별 배포 -> 로그 수집 -> 중앙 거버넌스
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Device/Sensor | 데이터 생성·1차 이벤트 | MCU, camera, PLC |
| Edge Node | 현장 인접 추론·제어 | p95 10~50ms 업무 |
| Fog Gateway | 프로토콜 변환·집계 | MQTT, OPC UA, Modbus |
| Regional Micro DC | 지역 단위 분석·캐시 | 장애 격리·정책 배포 |
| Cloud | 장기 저장·학습·통합 분석 | Data Lake, MLOps |

> 요약: 엣지는 현장 처리 노드이고, 포그는 엣지부터 지역 DC까지 묶는 중간 계층 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
센서 데이터 생성 -> 엣지 즉시 판단
-> 포그 게이트웨이 집계/필터링
-> 지역 노드 정책 적용
-> 클라우드 저장/학습
-> 정책 재배포와 지표 관측
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 현장 장비가 원천 데이터 생성 | sampling rate, event rate |
| 2 | 엣지 노드가 실시간 판단 | p95 latency, inference time |
| 3 | 포그 게이트웨이가 집계·정제 | 데이터 축소율, protocol error |
| 4 | 지역 노드가 정책·캐시 처리 | cache hit ratio, local SLA |
| 5 | 클라우드가 학습·장기 저장 | sync lag, data completeness |

> 요약: 데이터는 현장에서 즉시 줄이고, 지역에서 모아 판단하며, 클라우드에서 장기 분석한다.

---

## Ⅳ. 특징

| 구분 | 엣지 컴퓨팅 | 포그 컴퓨팅 | 판단 포인트 |
|:---|:---|:---|:---|
| 위치 | 단말·기지국·현장 서버 | 엣지와 클라우드 사이 계층 | 처리 지점 거리 |
| 구조 | 비교적 단일 현장 노드 | 다단 게이트웨이·지역 노드 | 계층 수와 라우팅 |
| 지연 | p95 10~50ms 업무 | 지역 집계 수십~수백 ms | 실시간 제어 여부 |
| 운영 | 노드별 배포 | 계층별 정책·관측 | 보안 경계와 버전 관리 |

> 요약: 엣지는 초저지연 현장 처리에, 포그는 다수 현장 데이터를 계층적으로 줄이고 통제하는 데 적합하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 엣지/포그 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 클라우드 집중 | 디바이스-엣지-포그-클라우드 | 데이터 발생량·지연 요구 |
| 비용/성능 | 중앙 자원 집중 | 분산 노드·네트워크 절감 | 원본 전송비 vs 노드 운영비 |
| 운영/위험 | 중앙 통제 단순 | 버전·인증·로그 분산 | GitOps, Zero Trust 필요 |

> 요약: 원본 데이터 전송 비용과 지연 요구가 클수록 엣지/포그 계층 분산이 타당하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 정책 불일치 | 계층별 설정 편차 | 중앙 정책 배포, GitOps | config drift count |
| 데이터 누락 | 오프라인·동기화 실패 | store-and-forward, 재전송 | sync lag, loss rate |
| 보안 경계 확대 | 노드 수 증가 | mTLS, TPM, OTA 서명 | 인증 실패율, CVE 조치 시간 |

> 요약: 분산 계층은 정책·데이터·보안 상태가 갈라지는 리스크를 지표로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연 | 제어 p95 50ms 이하 목표 | edge probe, APM |
| 데이터 절감 | 원본 대비 전송량 50% 이상 절감 목표 | gateway metric, traffic log |
| 운영 | 설정 편류 0건, 패치 SLA 7일 이내 | GitOps diff, vulnerability scan |

> 요약: 엣지/포그 도입은 지연, 데이터 절감률, 설정 편류를 함께 측정해 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 제어·탐지·집계·학습 업무를 p95 지연과 데이터량 기준으로 엣지, 포그, 클라우드에 분리 배치함
2. MQTT/OPC UA 게이트웨이, 컨테이너 런타임, OTA 서명 배포를 표준화해 계층별 버전 편차를 통제함
3. mTLS, TPM 기반 장비 신원, OpenTelemetry 로그 수집으로 분산 노드의 접근·상태·장애를 중앙에서 관측함

**결론 (2줄):**
- 기술사 판단: 즉시 제어는 엣지, 다수 현장 집계는 포그, 장기 학습은 클라우드로 배치하는 계층형 설계가 타당함
- 향후 방향: MEC, IoT, AI 추론이 결합되며 엣지-포그-클라우드는 컴퓨팅 컨티뉴엄 형태로 통합 운영됨
