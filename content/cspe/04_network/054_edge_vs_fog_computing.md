## 미리 알고가기

- 엣지 컴퓨팅은 데이터가 발생한 장치나 바로 옆 노드에서 처리하는 방식임
- 포그 컴퓨팅은 엣지와 클라우드 사이 여러 네트워크 노드에 처리를 분산하는 계층형 방식임
- 전처리는 원시 데이터에서 필요한 정보만 골라내는 현장 처리 단계임
- 오케스트레이션은 작업을 어느 노드에서 처리할지 정하고 배치하는 제어 기능임

## Ⅰ. 개요

- **정의/개념**: 엣지 컴퓨팅과 포그 컴퓨팅은 모두 클라우드 집중 처리의 지연 시간과 백홀 부담을 줄이기 위해 데이터 발생 지점 가까이로 연산을 분산하는 구조이며, 엣지는 끝단 중심이고 포그는 중간 계층 협업 중심이라는 차이가 있음
- **배경/필요성**: IoT와 실시간 제어 환경에서는 모든 데이터를 중앙으로 보내면 네트워크 비용이 커지고 즉시 반응이 어려우므로, 어디서 얼마만큼 처리할지 나눠 맡길 분산 구조가 필요함

## Ⅱ. 특징

- 두 방식 모두 현장 가까운 처리로 지연 시간과 전송량을 줄이려는 목적을 가짐
- 엣지는 즉시 반응과 단말 인접 처리가 중요할 때 강점을 보임
- 포그는 여러 엣지 노드를 묶어 지역 단위 집계와 협업 처리를 수행하기 좋음
- 두 기술 모두 클라우드를 대체하기보다 현장 처리와 중앙 분석을 분담하는 구조로 이해해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 엣지 컴퓨팅 | 포그 컴퓨팅 |
|:---|:---|:---|
| 처리 위치 | 단말 자체나 단말과 바로 붙은 게이트웨이, 기지국 근처에서 처리함 | 엣지와 클라우드 사이 라우터, 스위치, 지역 서버 같은 중간 계층에 분산 처리함 |
| 주요 목적 | 즉시 제어와 초저지연 반응에 초점을 둠 | 여러 현장 데이터를 지역 단위로 모아 조정하고 집계하는 데 강점이 있음 |
| 구조 성격 | 개별 노드 중심의 끝단 처리 구조임 | 계층형 노드들이 협업하는 중간 분산 구조임 |
| 적합 서비스 | 자율주행 제동, 기계 제어, 단말 근처 추론에 적합함 | 스마트시티 집계, 지역 이벤트 분석, 다수 엣지 조정에 적합함 |

> 요약: 엣지가 즉시 반응을 책임지는 끝단 처리라면 포그는 여러 엣지를 묶는 중간 협업 계층임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 발생 장치 | 센서, 카메라, 차량, 기계처럼 실시간 데이터를 만드는 출발점임 |
| 엣지 노드 | 단말 가까이에서 필터링, 추론, 제어를 수행하는 1차 처리 계층임 |
| 포그 노드 | 여러 엣지 데이터를 지역 단위로 모아 집계, 조정, 캐싱을 수행하는 중간 계층임 |
| 클라우드 | 장기 저장과 대규모 분석, 모델 학습을 담당하는 중앙 계층임 |
| 제어와 오케스트레이션 | 작업 분배와 정책 적용을 통해 어느 계층이 어떤 일을 맡을지 정하는 기능임 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 발생 장치 | --> | 엣지 노드      | --> | 포그 노드      | --> | 클라우드       |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| 현장 데이터 생성 | --> | 엣지 1차 처리     | --> | 포그 집계·조정     | --> | 클라우드 저장·학습 |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **현장 데이터 생성**: 센서와 장치가 원시 데이터를 지속적으로 만듦
2. **엣지 1차 처리**: 긴급 제어와 불필요 데이터 제거를 현장에서 먼저 수행함
3. **포그 집계와 조정**: 여러 엣지 데이터를 지역 단위로 모아 정책과 상태를 맞춤
4. **클라우드 저장과 학습**: 장기 분석과 모델 학습이 필요한 데이터만 중앙으로 보냄

## Ⅵ. 실무 적용 및 유의점

1. 즉시 제동이나 설비 보호처럼 반응 시간이 가장 중요한 환경에서는 포그 계층을 거치지 않고 엣지에서 바로 처리해야 하므로 제어 로직의 위치를 명확히 나누고 현장 응답 시간과 로컬 처리 비율로 확인함
2. 스마트시티, 유통 물류, 지역 관제처럼 여러 현장의 데이터를 묶어 봐야 하는 환경에서는 엣지만 두면 중복 처리와 정책 불일치가 생기므로 포그 계층에서 집계와 캐싱을 맡기고 지역 집계 지연 시간과 백홀 절감률로 확인함

## Ⅶ. 결론

엣지와 포그의 차이는 더 빠른 기술이 무엇이냐가 아니라 즉시 처리와 중간 협업 중 어느 역할이 필요한지에 있으므로 서비스 흐름에 맞춰 계층을 배치해야 함.
