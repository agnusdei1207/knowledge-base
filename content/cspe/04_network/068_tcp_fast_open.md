## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | TCP 3-Way Handshake 과정에서 연결 설정과 동시에 초기 데이터를 함께 전송하여 지연을 줄이는 확장 기술 |
| **배경/필요성** | HTTP/HTTPS와 같은 짧은 다중 연결 환경에서 불필요한 초기 연결 지연(1-RTT) 단축 필요 |
| **출제 의도** | TFO 쿠키 기반의 보안 연결 설정과 이를 통한 통신 지연 시간 감축 메커니즘 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+
|  Client  |       |  Server  |
| (Cookie) | <---> | (Crypto) |
+----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| TFO Cookie | 서버가 클라이언트 IP를 암호화하여 발급하는 신뢰 기반 재접속 토큰 | 빠른 입장 패스 |
| SYN 패킷 | 초기 연결 요청 시 데이터(Payload)를 쿠키와 함께 탑재하는 TFO 핵심 프레임 | 서류 동반 인사 |
| 3-Way 핸드 | 일반적인 TCP 연결 수립 절차를 우회하여 0-RTT 효과 달성 | 기존의 빈손 인사 |

> 요약: 쿠키 기반의 인증으로 3-Way Handshake 완료 전이라도 서버가 데이터를 즉각 처리하게 함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 초기 요청| -> | 쿠키 발급| -> | 재연결시 | -> | 즉시 처리|
+----------+    +----------+    +----------+    +----------+
```
1. 초기 요청: 클라이언트가 빈 TFO 옵션을 넣은 일반 SYN 패킷을 서버로 전송
2. 쿠키 발급: 서버는 클라이언트를 검증 후 고유 TFO 쿠키를 생성하여 SYN-ACK로 전달
3. 재연결시: 이후 동일 서버 접속 시 클라이언트는 SYN 패킷 내에 TFO 쿠키와 첫 요청 데이터 포함
4. 즉시 처리: 서버는 쿠키가 유효하면 핸드쉐이크 완료 전이라도 수신 데이터를 애플리케이션에 전달

> 요약: 초기 연결 시 쿠키를 교환하고, 재연결 시 이를 활용하여 첫 RTT부터 데이터를 교환함

## Ⅳ. 문제점
- 공격자가 탈취한 쿠키로 재전송 공격(Replay Attack)을 시도하여 서버 자원 고갈 유발 원인
- 중간 경로의 레거시 방화벽이나 NAT 장비가 비표준 SYN 데이터 패킷을 무단 드롭(미들박스 간섭)
- 분산 서버 환경(CDN)에서 노드 간 동일한 암호화 키가 동기화되지 않으면 쿠키 검증 실패

## Ⅴ. 개선방안
- [단기] 서버 측 쿠키 암호화 키의 주기적 갱신 및 동일 IP 단기 요청 건수(Rate Limit) 제어
- [중기] HTTP GET 메서드와 같이 부작용이 없는(Idempotent) 트랜잭션에만 엄격히 TFO 허용
- [장기] 태생적으로 연결 지연이 없고 미들박스 간섭이 없는 QUIC(UDP 기반) 프로토콜로 전면 전환

## Ⅵ. 전망
- 복잡한 TCP 확장 기술의 한계를 벗어나 QUIC 기반 통신으로 차세대 웹 인프라가 재편될 전망임
