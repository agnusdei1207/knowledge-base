## 미리 알고가기

- 서브넷: 하나의 IP 네트워크를 더 작은 논리 네트워크로 나눈 단위임
- 서브넷 마스크: IP 주소에서 네트워크 부분과 호스트 부분의 경계를 표시하는 값임
- CIDR: 클래스 고정 경계 대신 `/24`처럼 프리픽스 길이로 주소 블록을 표현하는 방식임
- VLSM: 필요한 호스트 수에 따라 서로 다른 프리픽스 길이를 배정하는 설계 방식임

## Ⅰ. 개요

- **정의/개념**: 서브네팅과 CIDR은 IP 주소 블록을 프리픽스 길이 기준으로 나누거나 묶어 주소 배정과 라우팅 범위를 조정하는 기법임
- **배경/필요성**: 고정 클래스 주소 체계는 주소 낭비와 라우팅 테이블 증가를 만들기 때문에 필요한 크기로 나누고 요약하는 설계 기준이 필요함

## Ⅱ. 특징

- 서브네팅은 호스트 비트 일부를 네트워크 비트로 사용해 하나의 주소 블록을 여러 망으로 나눔
- CIDR은 클래스 A/B/C 경계가 아니라 프리픽스 길이로 주소 범위를 표현함
- 경로 집약은 여러 세부 프리픽스를 상위 프리픽스 하나로 광고해 라우팅 항목을 줄임
- VLSM은 큰 서브넷부터 배정해야 주소 조각화를 줄일 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 서브네팅 | CIDR |
|:---|:---|:---|
| 주된 역할 | 하나의 네트워크를 여러 하위 네트워크로 나눔 | 주소 블록을 프리픽스 길이로 표현하고 집약함 |
| 설계 방향 | 내부 망 분리와 호스트 수 배정에 초점이 있음 | 프리픽스 표현과 주소 블록 조정에 초점이 있음 |
| 계산 기준 | 서브넷 수, 호스트 수, 마스크 길이를 계산함 | 프리픽스 길이와 블록 경계를 계산함 |
| 운영 효과 | 브로드캐스트 범위와 보안 경계를 나눌 수 있음 | 라우팅 테이블 항목을 줄일 수 있음 |

> 요약: 서브네팅은 내부 분할 기준이고 CIDR은 주소 표현과 경로 집약 기준임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 네트워크 비트 | 같은 서브넷에 속하는 주소 범위를 결정하고 라우팅 판단에 쓰임 |
| 호스트 비트 | 서브넷 내부에서 개별 인터페이스를 구분하는 영역임 |
| 프리픽스 길이 | 네트워크 비트 수를 `/n`으로 표시해 주소 블록 크기를 정함 |
| 브로드캐스트 주소 | IPv4 서브넷에서 모든 호스트에게 보내는 특수 주소이며 호스트에 할당하지 않음 |

```text
192.168.10.0/24
        split
192.168.10.0/26   192.168.10.64/26   192.168.10.128/26
```

> 요약: 프리픽스 길이를 늘리면 더 작은 서브넷이 되고, 줄이면 더 큰 주소 블록이 됨

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 요구산정  | --> | 블록계산  | --> | 주소배정  | --> | 경로요약 |
+----------+     +----------+     +----------+     +----------+
```

1. **요구산정**: 부서, 서비스, 보안 구역별 필요한 호스트 수를 계산함
2. **블록계산**: 필요한 호스트 수를 수용하는 프리픽스 길이와 블록 경계를 정함
3. **주소배정**: 큰 요구부터 주소 블록을 배정해 남는 공간을 관리함
4. **경로요약**: 연속된 하위 프리픽스를 상위 프리픽스로 묶어 광고함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 VPC를 설계할 때는 현재 인스턴스 수만 보고 작은 CIDR을 잡으면 확장 시 대역 충돌이 생기므로 여유 블록과 예약 대역을 두고 IP 사용률과 라우팅 테이블 크기로 확인함
2. 지사망을 여러 서브넷으로 나눌 때는 경로 집약이 가능한 연속 블록을 배정해야 하며 불연속 배정 여부와 요약 경로 수로 운영 부담을 확인함

## Ⅶ. 결론

서브네팅과 CIDR은 필요한 주소 규모, 확장 여유, 경로 집약 범위를 기준으로 프리픽스를 설계해야 함.

## 작성 근거(검토용)

- 이 키워드는 계산형으로 보이지만 기술사 답안에서는 주소 분할과 경로 집약의 설계 근거가 필요하므로 두 축을 분리함
- 주소 배정 판단은 주소 사용률, 라우팅 테이블 크기, 블록 연속성으로 확인 가능하게 바꿈
- 결론은 계산 공식 나열이 아니라 프리픽스 설계 판단을 회수함
