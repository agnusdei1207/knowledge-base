# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 서브네팅·CIDR은 IP 주소의 **네트워크/호스트 경계를 비트 단위로 조정**해 하나의 큰 대역을 필요한 크기로 잘게 나누거나(서브네팅) 여러 대역을 하나로 묶는(CIDR 집약) **주소 배분·경로 요약** 기법이다.
- **왜 필요한가**: 클래스(A/B/C) 고정 경계는 대역이 크거나 작아 주소를 낭비하고 라우팅 테이블을 키우므로, 경계를 자유롭게 잘라 주소를 아끼고 경로를 요약하기 위함이다.
- **핵심 직관**: 서브넷 마스크의 1의 개수(프리픽스 /n)를 늘리면 네트워크가 잘게 쪼개지고(서브넷 수 ↑, 호스트 수 ↓), 줄이면 여러 대역이 하나로 합쳐진다(집약).

## 핵심 용어 정리 (내부에 등장하는 것들)

주소의 옥텟·네트워크/호스트 부분·클래스 기본은 004에서 다뤘으므로, 여기서는 계산에 직결된 용어와 공식을 비유·워크드 예시로 먼저 푼다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 서브네팅 (Subnetting) | 큰 네트워크를 여러 작은 네트워크로 나눔. 호스트 비트를 빌려 네트워크 비트로 씀 | 큰 사무실을 칸막이로 여러 방으로 분할 |
| 서브넷 마스크 | 네트워크 부분을 1, 호스트 부분을 0으로 표시한 32비트 값 | 주소에 대는 형광펜 자(네트워크 칸 표시) |
| 프리픽스 (/n) | 마스크의 1의 개수. 네트워크 비트 수를 슬래시로 요약 | 형광펜 칠한 칸의 개수 |
| CIDR (Classless) | 클래스 경계를 버리고 /n으로 임의 비트에서 경계를 긋는 방식 | 규격 상자 대신 필요한 크기로 자르는 재단 |
| 비트 빌림 (Borrowing) | 서브네팅 시 호스트 비트 일부를 네트워크 식별용으로 전용 | 방을 늘리려 복도 공간을 방으로 편입 |
| 네트워크 주소 | 호스트 비트가 전부 0인 주소. 서브넷 자체를 식별 | 그 방의 문패(대표 주소) |
| 브로드캐스트 주소 | 호스트 비트가 전부 1인 주소. 서브넷 전체 전송 | 그 방 전체 방송 |
| 가용 호스트 수 | 2^(32−n) − 2. 네트워크·브로드캐스트 2개 제외 | 방 전체 자리 − 문패·스피커 2자리 |
| 서브넷 수 | 2^(빌린 비트). 빌린 비트 하나당 2배 증가 | 칸막이 하나 늘 때마다 방 2배 |
| VLSM (가변 길이) | 서브넷마다 다른 프리픽스를 적용해 크기를 딱 맞춤 | 인원수에 맞춰 방 크기를 제각각 배정 |
| 슈퍼네팅·집약 (Aggregation) | 여러 인접 대역을 짧은 프리픽스 하나로 묶어 경로 요약 | 여러 방을 하나의 층으로 묶어 안내 |
| 최장 프리픽스 일치 (LPM) | 라우팅 시 가장 긴 /n(가장 구체적) 경로를 선택 | 가장 자세한 주소 안내를 우선 |

**계산을 먼저 직관으로 풀어보기 (/26 예시)**
- `/26`은 마스크 앞 26비트가 1 → `255.255.255.192`. 호스트 비트는 32−26=6개.
- 가용 호스트 = 2⁶ − 2 = **62개**. 블록 크기 = 2⁶ = **64**.
- 그래서 `192.168.10.0/26`을 나누면 서브넷 경계는 64칸 간격: `.0`, `.64`, `.128`, `.192`.
- `.0/26` 서브넷 → 네트워크 `.0`, 브로드캐스트 `.63`, 사용 `.1~.62`.

## 깊이 이해
- **배경·문제의식**: 클래스풀 방식은 경계가 8/16/24비트로 고정돼, 300개 호스트가 필요하면 C클래스(254개)로 부족하고 B클래스(약 6.5만)를 쓰면 6만 개가 낭비됐다. 또 라우팅 테이블에 수많은 개별 네트워크가 실려 폭증했다. CIDR(1993, RFC 1519)은 경계를 임의 비트로 긋게 해 필요한 크기로 재단하고, 인접 대역을 하나로 집약해 라우팅 테이블을 줄였다.
- **작동 원리(어떻게+왜)**:
  - **서브네팅(비트 빌림)**: 호스트 비트 중 앞쪽 몇 개를 네트워크 식별용으로 빌린다. k비트를 빌리면 서브넷이 2ᵏ개로 늘고, 남은 호스트 비트가 줄어 서브넷당 호스트 수는 2^(호스트비트)−2로 감소한다. 왜 −2인가: 각 서브넷마다 호스트 전부 0(네트워크 주소)과 전부 1(브로드캐스트)은 장비에 못 준다.
  - **블록 크기 규칙**: 프리픽스가 정해지면 서브넷은 "블록 크기(2^호스트비트)" 간격으로 규칙적으로 배치된다. /26이면 64 간격, /27이면 32 간격. 이 규칙으로 임의 IP가 어느 서브넷·네트워크·브로드캐스트에 속하는지 암산할 수 있다.
  - **VLSM**: 모든 서브넷을 같은 크기로 자르면 큰 서브넷과 작은 서브넷이 섞인 실무에서 낭비가 크다. VLSM은 큰 그룹부터 큰 블록을 먼저 배정하고, 남은 대역을 다시 잘게 나눠 크기를 딱 맞춘다.
  - **집약(LPM)**: 반대로 인접 서브넷들(예: /24 네 개)을 상위 라우터에서 짧은 프리픽스(/22) 하나로 묶어 광고하면 라우팅 테이블이 줄어든다. 라우터는 여러 경로가 겹치면 가장 긴 프리픽스(가장 구체적)를 택한다.
- **비유**: 서브넷 마스크는 주소에 대는 "자"다. 자를 오른쪽으로 밀면(프리픽스 증가) 네트워크 칸이 넓어져 방이 많아지고 각 방은 작아진다. 왼쪽으로 당기면(집약) 여러 방이 한 층으로 합쳐진다.
- **구체 예시 (VLSM 배분)**: `192.168.1.0/24`를 부서별로 나눈다고 하자.
  - 영업 100대 → 128블록(/25, 126 가용) `.0~.127`
  - 개발 50대 → 64블록(/26, 62 가용) `.128~.191`
  - 관리 20대 → 32블록(/27, 30 가용) `.192~.223`
  - 링크(2대) → 4블록(/30, 2 가용) `.224~.227` … 남은 대역은 예비.
  - 큰 그룹부터 배정해야 조각화·낭비가 줄어든다.
- **흔한 오해·주의점**: `/31`은 예외적으로 점대점 링크에서 2개 주소를 모두 호스트로 쓴다(RFC 3021). "서브넷을 나누면 전체 호스트 수가 늘어난다"는 오해다 — 네트워크·브로드캐스트 예약이 서브넷마다 2개씩 생겨 오히려 총 가용 호스트는 줄어든다. IPv6는 주소가 충분해 보통 /64로 통일하므로 호스트 수 계산이 아니라 프리픽스 위임(경로 요약) 중심으로 서브네팅한다.

## 연결 개념
- IP 주소 체계(004) — 네트워크/호스트 분할·마스크의 기본 정의
- 라우팅(012)·BGP(015) — CIDR 집약과 최장 프리픽스 일치로 경로 결정
- IPv6 주소(004) — /64 고정 프리픽스, 프리픽스 위임 기반 서브네팅

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 서브네팅·CIDR은 네트워크/호스트 경계를 프리픽스(/n)로 조정해 대역을 분할·집약하는 주소 배분 기법임.
> 2. **가치**: 클래스 낭비를 없애 주소 활용률을 높이고, 집약으로 라우팅 테이블을 줄여 확장성을 확보함.
> 3. **판단 포인트**: 그룹별 소요 호스트에 맞춰 VLSM으로 크기를 최적화하고, 상위에서 집약해 경로를 요약함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 서브넷 계산 정확성 | 2^(32−n)−2, 블록 크기, 네트워크·브로드캐스트 | 가용 호스트 −2 누락, 블록 경계 오산 |
| CIDR·집약 이해 | 프리픽스 표기, 집약, 최장 프리픽스 일치 | 클래스풀과 혼동, 집약 방향 반대 서술 |
| VLSM 설계 역량 | 큰 그룹부터 가변 프리픽스 배분 | 모든 서브넷 동일 크기로 낭비 |

> 요약: 공식 암기가 아니라 소요 규모→프리픽스 산정→VLSM 배분→집약의 설계 흐름으로 서술함.

---

## Ⅰ. 개요 및 필요성

- 개요: 네트워크/호스트 경계를 프리픽스로 조정해 대역을 분할·집약하는 주소 배분 기법임
- 배경: (004 참조) 클래스 고정 경계가 주소를 낭비하고 라우팅 테이블을 폭증시킨 한계
- 필요성: VLSM으로 소요에 맞춰 주소를 절약하고, 집약으로 경로를 요약해 확장성을 확보하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
[프리픽스와 마스크]  /24 = 255.255.255.0   /26 = 255.255.255.192
[서브네팅]  192.168.10.0/24 → (호스트 2비트 빌림) → /26 4개
   .0/26(.1~.62) | .64/26 | .128/26 | .192/26   (블록 크기 64)
[집약]  .0/24 ~ .3/24 (4개) → 192.168.0.0/22 하나로 요약
```

| 구성요소 | 개념 | 주요 역할 | 계산·예시 |
|:---|:---|:---|:---|
| 프리픽스(/n) | 네트워크 비트 수 | 경계·마스크 결정 | /26 → 마스크 …192 |
| 블록 크기 | 2^(32−n) | 서브넷 간격·범위 산정 | /26 → 64 |
| 가용 호스트 | 2^(32−n) − 2 | 서브넷 수용 인원 | /26 → 62 |
| VLSM | 서브넷별 가변 프리픽스 | 소요에 맞춘 크기 배분 | 100대→/25, 20대→/27 |
| 집약(LPM) | 인접 대역 병합·최장일치 | 라우팅 테이블 축소 | 4×/24 → /22 |

> 요약: 프리픽스가 블록 크기·호스트 수를 결정하고, VLSM은 크기를 맞추며 집약은 경로를 요약함.

---

## Ⅲ. 동작원리 및 흐름도

```text
소요 호스트 산정 → 필요 프리픽스 결정(2^h−2≥소요) → 블록 경계로 서브넷 분할 → VLSM 배분 → 상위 집약
```

1. **소요 산정**: 각 그룹의 필요 호스트 수를 집계하고 여유율을 반영해 규모를 정함
2. **프리픽스 결정**: 소요를 만족하는 최소 호스트 비트 h를 골라 프리픽스 /(32−h)를 산정함
3. **경계 분할**: 블록 크기(2^h) 간격으로 네트워크·브로드캐스트를 구획해 서브넷을 나눔
4. **배분·집약**: 큰 그룹부터 VLSM으로 배정하고, 상위 라우터에서 인접 대역을 짧은 프리픽스로 집약함

> 요약: 소요→프리픽스→경계 분할→VLSM 배분→집약의 순서로, 낭비 없이 나누고 경로를 요약함.

---

## Ⅳ. 특징

- 주소 효율: VLSM으로 그룹별 크기를 딱 맞춰 클래스 대비 주소 낭비를 최소화함
- 경로 요약: 인접 대역 집약으로 광고 경로 수를 줄여 라우팅 테이블 규모를 축소함
- 유연 경계: 클래스 제약 없이 임의 비트에서 네트워크/호스트를 나눌 수 있음
- 예약 오버헤드: 서브넷마다 네트워크·브로드캐스트 2개가 예약돼 잘게 나눌수록 총 가용 호스트가 감소함
- 계산 규칙성: 블록 크기 간격으로 서브넷이 배치돼 임의 IP의 소속 서브넷을 암산으로 판별 가능함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 클래스풀(FLSM) | CIDR·VLSM |
|:---|:---|:---|
| 경계 | 8/16/24비트 고정 | 임의 비트(/n) |
| 주소 효율 | 낭비 큼 | 소요 맞춤 절약 |
| 라우팅 | 개별 광고 다수 | 집약으로 축소 |
| 유연성 | 서브넷 동일 크기 | 서브넷별 가변 |
| 계산 부담 | 단순 | 프리픽스·블록 산정 필요 |

> 요약: CIDR·VLSM은 계산 부담을 대가로 주소 절약·경로 요약을 얻어, 대규모 망 설계의 표준이 됨.

- 배분 리스크: 소규모부터 배정 시 조각화로 큰 블록 확보 실패 → 큰 그룹 우선 배분 원칙 적용
- 집약 리스크: 비인접 대역을 무리하게 묶으면 블랙홀·오라우팅 → 연속 정렬된 대역만 집약
- 관리 지표: 서브넷 활용률(할당 대비 사용), 라우팅 테이블 엔트리 수, 예비 대역 비율

## Ⅵ. 실무 적용 및 결론

- 계층적 주소 설계: 사이트→건물→부서로 프리픽스를 계층 배분해 상위에서 집약이 가능하도록 설계함
- VLSM 자동화: IPAM 도구로 소요 기반 프리픽스를 산정·할당하고 중복·유휴 대역을 추적함
- 링크 대역 절약: 점대점 구간은 /30 또는 /31로 배정해 호스트 예약 낭비를 최소화함
- 결론(조건부 판단): 그룹 규모 편차가 크면 VLSM으로 맞춤 배분하고, 상위는 집약해 테이블을 축소함이 유리함
- 결론(향후 방향): IPv6는 /64 통일·프리픽스 위임 중심이라, 호스트 수 계산보다 계층적 집약 설계가 관건이 됨
