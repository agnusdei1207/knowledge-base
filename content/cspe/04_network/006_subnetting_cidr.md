# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 커다란 IP 네트워크 하나를 적절한 크기로 쪼개거나(서브네팅), 여러 개를 합쳐서(CIDR) IP 주소를 알뜰하게 쓰는 기술
- **왜 필요한가**: 과거 A, B, C 클래스 방식은 기업에 IP를 통째로 줘서 수백만 개의 주소가 낭비되었다. 주소 고갈을 늦추기 위해 도입됨.
- **핵심 직관**: 큰 피자 한 판(Class)을 주문하지 않고, 2조각, 4조각, 8조각 등 먹을 만큼만 잘라서(Subnet/CIDR) 나누어주는 방식이다.

## 깊이 이해
- **배경·문제의식**: 1980년대 클래스(Class) 기반 주소 체계는 B클래스(6만 5천개 호스트)를 할당받은 회사가 1천 대만 쓰면 6만 4천 개가 버려졌다. 이를 해결하기 위해 네트워크를 잘게 쪼개는 서브네팅(Subnetting)이 등장했다.
- **작동 원리**: 
  - **서브네팅(Subnetting)**: Host 비트의 일부를 빌려 Network 비트로 쓴다. (네트워크 수는 늘어나고, 망당 호스트 수는 줄어듦)
  - **CIDR(Classless Inter-Domain Routing)**: 클래스 구분(A,B,C)을 완전히 없애고, `/24`, `/22`처럼 슬래시 표기법으로 네트워크 비트 길이를 마음대로 지정한다. (쪼개기도 하고 합치기도 가능)
- **비유**: 100층짜리 아파트를 A동, B동 통째로 분양하는 게 '클래스', 101호~105호 묶음으로 세밀하게 쪼개서 분양하는 게 '서브네팅/CIDR'이다.
- **구체 예시**: `192.168.1.0/24` (호스트 256개)를 서브네팅하여 `/26`으로 바꾸면, 호스트 64개짜리 네트워크 4개로 쪼개진다. 반대로 `/24` 4개를 합쳐 `/22` 하나로 만들면(슈퍼네팅), 라우팅 테이블이 1줄로 줄어든다.
- **흔한 오해·주의점**: 서브네팅은 주로 내부망(LAN)을 쪼갤 때 쓰고, CIDR은 통신사(ISP)에서 IP를 할당하거나 라우터 경로를 합칠 때 쓴다. 본질적으로 둘 다 서브넷 마스크(Subnet Mask)를 유연하게 쓰는 같은 원리다.

## 연결 개념
- 서브넷 마스크(Subnet Mask) — 어디까지가 네트워크인지 1로 표시하는 필터 (예: 255.255.255.0)
- 라우팅 테이블(Routing Table) — CIDR을 통해 경로를 요약(Route Summarization)하여 부하 감소
- VLSM (Variable Length Subnet Mask) — 부서별 호스트 수에 맞게 서브넷 크기를 다르게 자르는 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 서브네팅과 CIDR은 고정된 IP 클래스 체계의 비효율성을 극복하기 위해 서브넷 마스크 비트를 가변적으로 조절하는 IP 주소 할당 및 라우팅 기법이다.
> 2. **가치**: 불필요한 IP 주소 낭비를 막고(할당 효율성), 수많은 라우팅 경로를 하나로 축약(Route Summarization)하여 라우터의 메모리 및 처리 부하를 줄인다.
> 3. **판단 포인트**: 클라우드(VPC) 및 엔터프라이즈 망 설계 시 서브넷 대역을 업무와 보안 구역에 맞게 설계하여 브로드캐스트 도메인을 격리해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IP 주소 낭비 방지 원리 이해 | Host 비트를 Network 비트로 차용(Subnetting), 클래스 경계 제거(CIDR) | 클래스 A/B/C 정의만 길게 쓰고 CIDR 설명 부족 |
| 라우팅 최적화 관점 파악 | 경로 축약(Supernetting/Route Aggregation)을 통한 라우팅 테이블 축소 | 주소 할당 관점만 서술하고 라우팅 관점(BGP 연동) 누락 |
| 실무 네트워크 설계 역량 | VPC/Subnet 설계, VLSM을 활용한 가변 길이 할당 원리 | "네트워크가 빨라진다" 등 근거 없는 추상 표현 |

> 요약: 서브네팅은 내부 브로드캐스트 통제를 위한 '분할'이며, CIDR은 라우팅 부하 감소를 위한 '분할 및 병합'이라는 양면성을 보여주어야 한다.

## Ⅰ. 개요 및 필요성

- 정의: IP 주소의 Network 영역과 Host 영역의 경계를 가변적으로 조절하여 대역폭을 분할하거나 병합하는 주소 체계 기술
- 배경: 기존 Classful(A/B/C) 할당 방식은 획일적 크기로 인해 IP 주소가 심각하게 낭비되고 라우팅 테이블이 기하급수적으로 증가함
- 필요성: IP 할당의 효율성 극대화, 브로드캐스트 도메인 축소로 네트워크 부하 방지, 라우팅 테이블 요약(Summarization)

---

## Ⅱ. 구조 및 구성요소

```text
Classful 구조: [Network ID 고정 (8/16/24)] | [Host ID]
                      ↓ (Subnetting / CIDR 적용)
Classless 구조: [Network ID] | [Subnet ID] | [Host ID]
                <---- Prefix (예: /26) ---->
```

| 구분 | 개념 및 원리 | 주요 목적 | 표기법 예시 |
|:---|:---|:---|:---|
| 서브네팅 (Subnetting) | 하나의 네트워크를 더 작은 여러 서브넷으로 분할 (Host 비트 차용) | 브로드캐스트 격리, 보안 구역 분리 | 255.255.255.192 |
| 슈퍼네팅 (Supernetting) | 여러 연속된 작은 네트워크를 하나의 큰 네트워크로 병합 | 라우팅 테이블 엔트리 수 감소 | 192.168.0.0 ~ 3.0 병합 |
| CIDR | 클래스 구분을 폐지하고 Prefix 길이로 네트워크 크기 유연 할당 | IP 낭비 최소화, 글로벌 라우팅 지원 | 10.10.10.0/22 |
| VLSM | 동일 망 내에서 호스트 요구 수에 따라 서브넷 크기를 다르게 분할 | 가변적 서브네팅으로 자원 극대화 | /25, /26, /30 혼용 |

> 요약: 서브네팅과 VLSM은 네트워크 내부망 구조를 최적화하며, 슈퍼네팅과 CIDR은 외부 라우팅 인프라의 처리 부하를 경감시킨다.

---

## Ⅲ. 동작원리 및 흐름도

```text
IP 할당 요구 (예: 60대) -> 필요한 Host 비트 계산 (2^6-2 = 62대) -> /26 서브넷 마스크 적용 
-> Network ID(192.168.1.64) 산출 -> 라우터에 분할된 대역 라우팅 적용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | **요구사항 분석** | 부서/용도별 필요 IP 호스트 수량(n) 파악 |
| 2 | **Host 비트 산정** | 2^h - 2 >= n 수식을 만족하는 최소 h(Host bit) 계산 |
| 3 | **서브넷/CIDR 지정** | 32 - h = Prefix 길이(CIDR 표시, 예: /26) 확정 |
| 4 | **주소 할당 및 라우팅** | Network 주소 및 Broadcast 주소 제외 후 호스트 IP 배포 |

> 요약: 호스트 수에 맞춘 정확한 비트 분할(Subnetting)을 통해 브로드캐스트 도메인을 최소화하고 대역폭 낭비를 막는다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 라우팅 테이블 축약 | 인접한 여러 개의 서브넷 대역을 상위 라우터에서 하나의 CIDR 블록으로 요약 광고 | 라우터 메모리 점유율 및 검색 룩업(Lookup) 속도 향상 |
| 브로드캐스트 억제 | 거대한 망을 서브네팅하면 브로드캐스트 패킷이 라우터 경계에서 차단됨 | 네트워크 혼잡(Broadcast Storm) 방지 |
| IP 가용성 제약 | 서브넷을 나눌 때마다 Network ID, Broadcast ID로 인해 2개씩 사용 불가 IP 발생 | 과도한 잘게 쪼개기(Fragment) 경계 |

> 요약: CIDR은 주소 효율성과 라우팅 성능 두 마리 토끼를 잡았지만, 지나치게 세분화된 VLSM 설계는 IP 관리 복잡도를 증가시킨다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Classful 주소 체계 (과거) | CIDR / VLSM 체계 (현재) | 선택 기준 |
|:---|:---|:---|:---|
| 할당 단위 | A(/8), B(/16), C(/24) 고정 크기 | /1 부터 /32 까지 비트 단위 가변 | 사용자/기업의 실제 단말 수 |
| 라우팅 프로토콜 | RIPv1, IGRP (Subnet 마스크 광고 안 함) | OSPF, BGP, RIPv2 (Subnet 마스크 포함 광고) | 장비 지원 여부 (현재는 모두 후자) |
| 라우팅 최적화 | 라우팅 경로 요약 불가 (원시 대역 유지) | Route Summarization 적극 활용 | 백본 라우터의 BGP 라우팅 부하 |

> 요약: 현대 인터넷 라우팅은 BGP(Border Gateway Protocol)와 CIDR의 결합 없이는 전 세계 100만 개 이상의 경로를 감당할 수 없다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 라우팅 블랙홀 | 잘못된 CIDR 요약 설정으로 비어있는 IP 대역까지 광고 | 정확한 비트 연계(Boundary) 확인 후 Aggregation 설정 | 라우팅 테이블 내 Unreachable Drop 로그 |
| IP 고갈 (내부) | 잘못된 설계로 특정 서브넷 IP 소진(예: Kubernetes Pod 확장 시) | VPC 설계 시 퍼블릭/프라이빗 용도별 여유 CIDR 블록 확보 | Subnet IP 사용률 80% 임계치 |
| 겹침(Overlap) 발생 | 본사-지사 간, 혹은 VPC Peering 시 동일 CIDR 대역 할당 | 전사 IPAM(IP Address Management) 솔루션을 통한 IP 할당 통제 | 라우팅 테이블 충돌(Conflict) 여부 |

> 요약: 서브넷 설계 실패는 클라우드 아키텍처에서 서비스 확장을 불가능하게 만드는 치명적 장애를 유발하므로 초기 여유 설계가 필수적이다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **퍼블릭 클라우드 VPC 설계**: AWS/GCP 환경에서 /16 대역의 VPC를 생성하고, 웹(Public /24), WAS/DB(Private /24)로 서브네팅하여 보안 구역(Tier) 분리
2. **사내망 VLSM 기반 할당**: 부서별 인원 규모에 따라 R&D 부서는 /24(254명), 관리 부서는 /26(62명), 스위치 간 연결(P2P)은 /30(2대)으로 가변 할당
3. **BGP 경로 요약(Aggregation)**: 여러 지사의 /24 대역(10.1.0.0/24 ~ 10.1.3.0/24)을 상위 ISP 라우터로 광고 시 10.1.0.0/22 하나로 묶어 라우팅 테이블 축소

**결론 (2줄):**
- 기술사 판단: 서브네팅과 CIDR은 단순한 계산법이 아니라, 브로드캐스트 도메인 크기를 결정하여 네트워크 성능과 보안 아키텍처를 결정짓는 근간 기술이다.
- 향후 방향: IPv4 환경에서는 필수적이며, IPv6 환경에서도 엄청난 주소 공간을 계층적으로 라우팅(Hierarchical Routing)하기 위해 CIDR의 /48, /64 분할 개념이 동일하게 적용된다.

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 설명형 | "서브네팅과 CIDR을 설명하시오" | 서브넷 마스크 비트 연산 방식 및 할당 흐름 | Classful과 CIDR의 라우팅 효율성 비교 |
| 설계형 | "VPC 네트워크 설계 방안을 제시하시오" | 용도별 IP 요구량 계산 및 티어(Tier)별 서브네팅 분할 | 퍼블릭/프라이빗 격리, 라우팅 테이블 축약, IPAM 관리 |

> 요약: 설명형은 IP 낭비를 막는 원리 수식(h 비트)에 집중하고, 클라우드 등 설계형 문제는 보안 분리와 라우팅 확장성(VPC Peering 시 충돌 방지)에 초점을 맞춘다.
