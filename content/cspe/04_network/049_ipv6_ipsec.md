## Ⅰ. 개요
- **정의**: IPv6는 128비트 주소 공간을 갖는 차세대 인터넷 프로토콜이며, IPSec은 네트워크(L3) 계층에서 패킷의 기밀성, 무결성, 인증을 제공하는 보안 프레임워크임.
- **배경/필요성**: IPv4의 주소 고갈 문제 완벽 해결 및 상위 애플리케이션 변경 없이 투명한 종단 간(End-to-End) 암호화 통신 필요.
- **출제 의도**: IPv6의 특징(주소 확장, 헤더 간소화) 및 IPSec의 두 가지 주요 프로토콜(AH/ESP), 그리고 터널/전송 모드 구별.

## Ⅱ. 구성요소
```text
+-----------------------------------------------+
|             IPv6 IPSec Packet (ESP)           |
| +-------------+-------+----------+----------+ |
| | New IPv6 Hdr|  ESP  | 원본 IP  | Payload  | |
| | (터널 모드) | Header| Header   | (암호화) | |
| +-------------+-------+----------+----------+ |
+-----------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| IPv6 Header | 송수신지 128비트 IP 주소를 담고 있으며, 가변 옵션을 분리하여 기본 헤더 크기를 고정/간소화 | 규격화된 택배 상자 |
| AH (Auth Header) | 데이터의 무결성과 출발지 인증을 제공하나, 페이로드를 암호화하지는 않음 (기밀성 X) | 봉인 씰(Seal) 부착 |
| ESP (Encapsulating)| 페이로드 암호화(기밀성)와 무결성, 인증을 모두 제공하는 핵심 IPSec 프로토콜 | 비밀번호 걸린 금고 |
> 요약: IPv6가 넓은 길과 주소를 제공하고, IPSec(ESP)이 그 길 위를 달리는 데이터 패킷을 암호화 장갑차로 보호함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 키 교환   |-> | SA 수립     |-> | 암호화/전송 |-> | 검증/복호화|
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **키 교환**: 송수신 양단 장비가 IKE(Internet Key Exchange) 프로토콜을 사용하여 암호화 통신에 쓸 대칭키를 안전하게 교환함.
2. **SA 수립**: 암호화 알고리즘, 수명 시간 등 보안 정책 협상을 완료하여 논리적 터널인 보안 연관(Security Association)을 구축함.
3. **암호화/전송**: 전송할 원본 IP 패킷 전체(터널 모드) 또는 페이로드(전송 모드)를 ESP로 암호화하여 IPv6 망을 통해 전송함.
4. **검증/복호화**: 목적지 라우터/단말에서 무결성 해시를 검증한 후, 암호를 해독하여 원본 데이터를 추출함.
> 요약: 터널을 뚫기 전 비밀번호(키)를 합의하고, 합의된 방식으로 패킷을 포장(암호화)하여 안전하게 배송함.

## Ⅳ. 문제점
- **과도한 오버헤드**: 패킷마다 암/복호화 및 해시 연산이 수행되므로 네트워크 장비(라우터/방화벽)의 CPU 부하와 전송 지연 발생.
- **NAT와의 충돌**: 터널 중간에 IPv4 NAT 환경이 존재할 경우 포트 정보가 암호화되거나 무결성 검사가 실패하여 통신 단절 문제 발생.
- **IPv4 인프라 전환 지연**: 듀얼 스택 유지 및 변환(NAT64 등) 복잡성으로 인해 순수 IPv6 단일 망으로의 전환이 전 세계적으로 매우 더딤.

## Ⅴ. 개선방안
- **호환성 확보**: NAT 통과 문제를 해결하기 위해 UDP 4500 포트로 캡슐화하는 NAT-T(NAT Traversal) 기능 활성화 (단기).
- **성능 고속화**: IPSec 처리 부하를 덜기 위해 하드웨어 암호화 가속기(Crypto-Engine/ASIC) 탑재 전용 VPN 장비 도입 (중기).
- **제로 트러스트 연계**: L3 중심의 IPSec VPN에서 벗어나, L7 애플리케이션 단위의 마이크로 터널링 및 ZTNA 모델로 보안 패러다임 전환 (장기).

## Ⅵ. 전망
- 5G 코어망, 사물인터넷(IoT), 스마트 시티 인프라 확장에 따라 IPv6의 주소 공간과 IPSec 내장 보안의 중요성은 지속 증대됨.
- 다만 클라이언트 원격 접속 환경에서는 무거운 IPSec보다 가볍고 방화벽 친화적인 SSL/TLS VPN 또는 WireGuard 프로토콜이 더 선호되고 있음.
