# 📖 【암기용】 개념 완전 이해

> 목적: Wi-Fi 7을 MLO와 6GHz 대역 중심으로 이해하게 만든다. 시험 답안 양식이 아니라, 802.11be의 도입 이유와 운영 조건을 잡기 위한 설명이다.

## 한눈에
- **개요**: Wi-Fi 7은 IEEE 802.11be 기반의 무선 LAN 세대로 MLO, 320MHz, 4096-QAM을 제공
- **왜 필요한가**: AR/VR, 실시간 협업, 고밀도 회의실은 평균 처리량보다 p95 지연, 재전송률, 링크 가용성이 더 민감함.
- **핵심 직관**: Wi-Fi 7은 하나의 무선 길만 쓰지 않고 2.4/5/6GHz 여러 길을 동시에 보며 막히지 않는 길로 데이터를 보내는 구조임.

## 깊이 이해
- **배경·문제의식**: Wi-Fi 6E는 6GHz를 사용하지만 단일 링크 기반 제약이 남음. 링크 하나의 간섭이나 DFS 이벤트가 전체 경험에 영향을 줄 수 있음.
- **작동 원리**: MLO(Multi-Link Operation)는 단말과 AP가 여러 밴드 링크를 묶어 동시 전송, 부하 분산, 링크 전환을 수행함. 6GHz에서는 넓은 320MHz 채널을 사용할 수 있어 대용량 전송에 유리함.
- **비유**: 출근길에 지하철 한 노선만 타는 대신 지하철, 버스, 택시를 동시에 보고 가장 지연이 작은 경로를 선택하는 방식임.
- **구체 예시**: Wi-Fi 7은 802.11be, 최대 320MHz 채널, 4096-QAM, Multi-RU, puncturing, MLO를 특징으로 함.
- **흔한 오해·주의점**: Wi-Fi 7 AP만 교체해도 모든 단말이 MLO를 쓰는 것은 아님. 단말 칩셋, OS, 6GHz 규제, WPA3 지원이 필요함.

## 연결 개념
- Wi-Fi Standards: 802.11ax와 802.11be 비교
- OFDMA·Multi-RU: RU 할당과 Multi-RU 기반
- WPA3/6GHz: 6GHz 접속 보안 조건

## Ⅰ. 개요 및 필요성

- 개요: IEEE 802.11be 기반으로 MLO·6GHz·320MHz를 제공하는 무선 LAN 표준
- 배경: MLO로 2.4/5/6GHz 여러 링크를 동시에 사용해 단일 링크 간섭·DFS 이벤트의 영향을 줄임
- 필요성: 고밀도·저지연 업무에서는 AP 세대 교체뿐 아니라 단말, 채널, 백홀, 보안 정책의 동시 설계가 필요함

---

## Ⅱ. 구조 및 구성요소

```text
Wi-Fi 7 STA -> Multi-Link Device -> 2.4GHz Link
                                  -> 5GHz Link
                                  -> 6GHz Link -> Wi-Fi 7 AP -> 2.5/5/10GbE Backhaul
          / MLO Scheduler
          / 320MHz Channel
          / WPA3
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MLD | 여러 링크를 하나의 장치로 관리 | AP MLD, non-AP MLD |
| MLO | 동시 전송·부하 분산·링크 전환 | 지연 민감 트래픽에 활용 |
| 6GHz | 넓은 채널과 낮은 legacy 간섭 | 국가별 허용 채널 확인 |
| 320MHz | 대역폭 확장 | 6GHz 중심 활용 |
| 4096-QAM | 변조 밀도 증가 | 높은 SNR 필요 |

> 요약: Wi-Fi 7 구조는 단말과 AP가 여러 링크를 묶고 MLO 스케줄러가 대역·지연·간섭 조건에 따라 전송을 배분함.

---

## Ⅲ. 동작원리 및 흐름도

```text
단말 capability 교환 -> multi-link setup -> 링크별 채널 품질 측정
-> MLO scheduler 선택 -> 동시/전환 전송 -> QoS·재전송 지표 수집
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AP와 단말이 802.11be capability 교환 | MLO support |
| 2 | 2.4/5/6GHz 링크를 multi-link로 설정 | link count |
| 3 | 채널별 RSSI, SNR, utilization 측정 | RF telemetry |
| 4 | 트래픽별 동시 전송 또는 링크 전환 수행 | p95 latency |
| 5 | 재전송·roaming·백홀 병목을 점검 | retry, uplink usage |

> 요약: Wi-Fi 7은 multi-link 설정 후 링크 품질을 측정해 트래픽을 여러 대역에 배분하거나 전환함.

## Ⅳ. 특징

| 구분 | Wi-Fi 6/6E | Wi-Fi 7 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 표준 | IEEE 802.11ax | IEEE 802.11be | Wi-Fi Alliance Wi-Fi 7 |
| 채널 폭 | 최대 160MHz | 최대 320MHz | 6GHz 활용 |
| 변조 | 1024-QAM | 4096-QAM | 높은 SNR 필요 |
| 링크 | 단일 링크 중심 | MLO 다중 링크 | multi-link operation |
| 간섭 대응 | BSS Coloring | puncturing, MLO steering | 채널 일부 회피 |

> 요약: Wi-Fi 7은 802.11be의 MLO와 320MHz 채널로 용량과 지연 제어 선택지를 확대함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | Wi-Fi 7 적용 | 선택 기준 |
|:---|:---|:---|:---|
| 고밀도 회의실 | Wi-Fi 6 | Wi-Fi 7 MLO | 동시 단말 50대 이상 |
| AR/VR | 단일 5GHz 링크 | 6GHz+MLO | p95 지연 20ms 이하 |
| 백홀 | 1GbE AP uplink | 2.5/5/10GbE | AP aggregate throughput |

> 요약: Wi-Fi 7은 단말 밀도와 지연 목표가 명확할 때 백홀 증설과 함께 적용해야 함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| MLO 미활용 | 단말·OS 미지원 | 단말 inventory, SSID 정책 | MLO capable client ratio |
| 6GHz 음영 | 전파 감쇠·규제 제한 | AP 재배치, 5GHz fallback | 6GHz RSSI, roaming |
| 백홀 병목 | AP radio 대비 uplink 부족 | 2.5GbE 이상, switch PoE 예산 | uplink utilization |

> 요약: Wi-Fi 7 리스크는 단말 지원, 6GHz 커버리지, 유선 백홀 병목이며 사전 조사로 판단함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연 | p95 latency 20ms 이하 | active probe, controller |
| MLO 적용 | 지원 단말 중 80% 이상 | WLAN telemetry |
| 재전송 | retry rate 10% 이하 | AP radio counter |

> 요약: Wi-Fi 7 효과는 최고 PHY rate가 아니라 지연, MLO 적용률, 재전송률로 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 사전 조사: 6GHz 허용 채널, 단말 802.11be/MLO 지원률, WPA3 요구사항, AP 전원(PoE) 예산 확인
2. RF 설계: 6GHz RSSI -65dBm 이상 구역을 목표로 AP 배치, 320MHz 사용 구간과 80/160MHz fallback 구간 분리
3. 운영 검증: MLO 적용률, p95 latency, retry rate, 2.5/5/10GbE uplink 사용률을 controller 대시보드에 반영

**결론 (2줄):**
- 기술사 판단: AR/VR·고밀도·저지연 업무는 Wi-Fi 7, 일반 사무·legacy 단말 중심 환경은 Wi-Fi 6/6E를 유지하며 단계 전환함
- 향후 방향: Wi-Fi 7은 6GHz와 MLO를 기반으로 기업 무선망의 지표를 처리량 중심에서 지연·링크 가용성 중심으로 바꿈
