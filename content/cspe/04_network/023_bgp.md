## Ⅰ. 개요
- **정의**: AS(자율 시스템) 간 경로 정보를 교환하는 Path Vector 기반 EGP
- **배경/필요성**: 인터넷은 수만 개 AS로 구성되어 있어 AS 간 정책 기반 경로 선택 메커니즘이 필요함
- **비유**: 국가 간 항공 노선을 경유지 목록과 외교 정책에 따라 결정하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| iBGP/eBGP 차이와 정책 라우팅 이해 | AS-Path 속성과 경로 선택 알고리즘 | BGP는 최단 경로가 아닌 정책 기반 선택임을 명확히 할 것 |

> 요약: 인터넷 AS 간 정책 기반 경로 교환을 담당하는 유일한 EGP임

## Ⅱ. 구성요소
```text
AS 100 ---eBGP--- AS 200 ---eBGP--- AS 300
  |                 |
 iBGP              iBGP
  |                 |
Router A          Router B
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| AS-Path | 경로가 경유한 AS 번호 목록으로 루프 방지에 활용됨 | 택배 송장의 경유지 목록 |
| BGP Attribute | Local Pref, MED, Weight 등 경로 선택 기준 속성 집합 | 항공편 선택 시 가격·시간·경유지 조건 |
| BGP Peer | TCP 179 포트로 세션을 맺는 인접 BGP 라우터 | 항공사 간 코드셰어 협정 파트너 |
| RIB | 수신·최적·송신 경로를 구분 저장하는 라우팅 정보 베이스 | 후보 노선·확정 노선·공유 노선 목록 |

> 요약: AS-Path·Attribute·Peer·RIB가 정책 기반 경로 결정의 핵심 요소임

## Ⅲ. 절차
```text
TCP 연결 --> OPEN 교환 --> UPDATE 전송 --> 최적 경로 선택 --> 라우팅 반영
```
- 1단계: TCP 3-Way Handshake로 피어 간 세션을 수립함
- 2단계: OPEN 메시지로 AS 번호·Hold Time 등 파라미터를 협상함
- 3단계: UPDATE 메시지로 경로 정보(NLRI + Attribute)를 교환함
- 4단계: 13단계 경로 선택 알고리즘(Weight > Local Pref > AS-Path 등)으로 최적 경로를 결정함

> 요약: TCP 세션 수립 후 UPDATE 교환과 다단계 선택 알고리즘으로 경로를 확정함

## Ⅳ. 문제점
- 수렴 지연: 대규모 인터넷에서 경로 변경 전파에 수 분이 소요되어 일시적 블랙홀이 발생함
- 보안 취약: BGP Hijacking으로 잘못된 경로 광고가 트래픽을 탈취할 수 있음
- iBGP Full-Mesh: N개 라우터 시 N(N-1)/2 세션이 필요하여 관리 부담이 큼

> 요약: 수렴 지연·보안 취약·Full-Mesh 복잡성이 주요 과제임

## Ⅴ. 개선방안
1. 단기: BGP Timer 튜닝과 Graceful Restart로 수렴 시간을 단축함
2. 중기: RPKI(Resource PKI) 도입으로 경로 원본 인증을 적용함
3. 장기: Route Reflector·Confederation으로 iBGP Full-Mesh를 제거함

> 요약: 타이머 최적화·RPKI·RR 구조로 단계적 개선이 가능함

## Ⅵ. 전망
- 발전 방향: BGP-LS와 SDN 컨트롤러 연계로 중앙 집중형 트래픽 엔지니어링이 확대됨
- 기술사적 판단: 인터넷 라우팅의 유일한 표준으로 대체 불가하며, 보안 강화가 최우선 과제임
- 기술사 제언: RPKI 적용 현황과 BGP-LS 기반 SDN 연동 구조를 함께 파악할 필요
