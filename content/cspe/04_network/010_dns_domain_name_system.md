# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 숫자로 된 IP 주소(예: 142.250.x.x)를 사람이 기억하기 쉬운 도메인 이름(예: google.com)으로 바꿔주는 **네트워크의 '이름 해석' 시스템**입니다.
- **필요성**: 수많은 웹사이트의 IP를 일일이 외울 수 없으며, 서버의 위치가 바뀌어 IP가 변경되더라도 이름(도메인)은 그대로 유지하여 서비스 연속성을 보장하기 위해 필수적입니다.
- **핵심 직관**: **"디지털 전화번호부"**. 이름을 검색하면 번호를 알려주고, 번호가 바뀌어도 이름으로 찾을 수 있게 해줍니다.

## 깊이 이해
- **배경 (중앙 집중에서 분산으로)**: 초기에는 `hosts.txt` 파일 하나에 모든 매핑을 적어 공유했지만, 인터넷이 커지자 파일 크기가 너무 커지고 업데이트가 불가능해졌습니다. 그래서 **계층적 분산 구조**인 DNS가 탄생했습니다.
- **작동 원리 (계층적 추적)**:
  - **Root DNS**: 트리 최상위(`.`). "다음은 .com 서버로 가보세요"라고 안내합니다.
  - **TLD (Top Level Domain) DNS**: `.com`, `.net`, `.kr` 등을 관리합니다.
  - **Authoritative DNS**: 실제 'naver.com' 같은 특정 도메인의 IP 정보를 가진 최종 책임 서버입니다.
- **질의 방식**:
  - **Recursive (재귀적)**: 단말이 Local DNS에게 "끝까지 알아다 줘"라고 맡기는 방식.
  - **Iterative (반복적)**: Local DNS가 Root부터 차례대로 "여기에 있나요?"라고 직접 물어보며 찾아가는 방식.
- **비유 (도서관 책 찾기)**:
  - **안내 데스크(Root)**: "컴퓨터 서적은 3층(TLD)으로 가세요."
  - **3층 담당자(TLD)**: "네트워크 책은 5번 서가(Auth)에 있습니다."
  - **5번 서가(Auth)**: "찾으시는 책(IP)은 여기 7번에 있네요."

## 연결 개념
- **TTL (Time To Live)**: DNS 정보를 내 메모리(캐시)에 얼마나 오래 저장해둘지 정하는 시간.
- **DNSSEC**: DNS 응답에 디지털 서명을 붙여 가짜 주소를 알려주는 공격(DNS Poisoning)을 막는 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 계층적 트리 구조와 분산 데이터베이스를 활용하여 도메인 이름과 IP 주소를 상호 매핑하는 네트워크 인프라 서비스임.
> 2. **가치**: 캐싱과 위임(Delegation)을 통해 전 세계 수조 건의 질의를 효율적으로 분산 처리하며, GSLB 등 글로벌 부하분산의 핵심 기제로 작동함.
> 3. **판단 포인트**: 최근에는 개인정보 보호를 위한 DNS 암호화(DoH, DoT)와 위변조 방지를 위한 DNSSEC 도입이 보안 설계의 필수 요소임.

## Ⅰ. DNS의 정의 및 계층적 분산 구조
- **정의**: 호스트의 도메인 이름을 IP 주소로 변환하거나 그 반대의 역할을 수행하는 분산 데이터베이스 시스템.
- **계층 구조 (Root-TLD-Authoritative)**:
  - **Root DNS**: 전 세계 13개(논리적) 서버 운영, 하위 TLD 서버 정보 제공.
  - **TLD (Top Level Domain)**: `.com`, `.net` 등 일반 도메인과 `.kr`, `.jp` 등 국가 도메인 관리.
  - **Authoritative DNS**: 특정 도메인의 정답(A, MX 레코드 등)을 보유한 서버.

## Ⅱ. DNS 질의(Query) 프로세스 상세 분석

### 1. 재귀적(Recursive) vs 반복적(Iterative) 질의
- **Recursive Query**: 클라이언트(PC)와 Local DNS(ISP) 간의 질의. "최종 결과를 알려달라"는 요청.
- **Iterative Query**: Local DNS가 Root, TLD, Auth 서버를 차례로 방문하여 정보를 획득하는 과정.

### 2. 단계별 해석 흐름 (Name Resolution)
1. 클라이언트가 Local DNS에 질의 (`www.google.com`이 누구니?)
2. Local DNS가 Root에 질의 -> Root가 `.com` TLD 주소 응답.
3. Local DNS가 TLD에 질의 -> TLD가 `google.com` 권한 서버 주소 응답.
4. Local DNS가 Auth 서버에 질의 -> **A 레코드(IP)** 정답 수신.
5. Local DNS가 클라이언트에 전달 및 결과 **캐싱(TTL 적용)**.

## Ⅲ. 주요 DNS 리소스 레코드(Resource Record) 유형

| 레코드 종류 | 기능 | 설명 |
|:---:|:---|:---|
| **A (Address)** | 도메인 → IPv4 | 호스트 이름을 IPv4 주소로 매핑 |
| **AAAA** | 도메인 → IPv6 | 호스트 이름을 IPv6 주소로 매핑 |
| **CNAME** | Canonical Name | 도메인 이름에 대한 별칭(Alias) 지정 |
| **MX** | Mail Exchanger | 해당 도메인의 이메일 수신 서버 지정 |
| **NS** | Name Server | 해당 도메인의 권한(Authoritative) 서버 지정 |
| **TXT** | Text Record | SPF 등 인증 정보나 기타 텍스트 데이터 포함 |

## Ⅳ. DNS 보안 위협 및 고도화 기술

### 1. DNS Cache Poisoning (위조 공격)
- **위협**: 가짜 DNS 응답을 캐시 서버에 주입하여 사용자를 피싱 사이트로 유도.
- **대응**: **DNSSEC** 도입. 공개키 암호화 기반 전자서명을 통해 응답 데이터의 무결성 검증.

### 2. DNS 암호화 및 프라이버시 보호
- **DoT (DNS over TLS)**: 전용 포트(853)를 통해 DNS 질의를 TLS로 암호화.
- **DoH (DNS over HTTPS)**: HTTPS 포트(443)를 통해 질의를 전달하여 감청 및 차단 우회.

## Ⅴ. DNS 기반 부하분산 및 응용 기술 (GSLB)
- **GSLB (Global Server Load Balancing)**:
  - 사용자의 위치, 서버의 상태, 네트워크 가용성을 판단하여 최적의 서버 IP를 응답.
  - 서비스 가용성 확보(Health Check) 및 응답 속도 최적화(Geo-location) 가능.

## Ⅵ. 기술사적 통찰: '보이지 않는 지휘자'
- **중앙 통제의 한계**: Root DNS의 안정성이 인터넷 전체의 안정성을 결정하므로, 애니캐스트(Anycast) 기술을 통해 13개의 논리 서버를 전 세계 수백 개의 물리 서버로 분산 배치하여 가용성 극대화.
- **클라우드 네이티브 네이밍**: 쿠버네티스의 CoreDNS 등 현대적 환경에서는 서비스의 생성과 삭제에 따라 DNS 레코드가 초 단위로 업데이트되는 'Dynamic DNS' 역량이 서비스 메쉬 아키텍처의 핵심이 됨.
- **결론**: DNS는 단순한 주소 변환기를 넘어, 인터넷의 트래픽 흐름을 조절하고 보안 경계를 정의하는 **"인터넷의 가장 정교한 내비게이션 시스템"**임.
