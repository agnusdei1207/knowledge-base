## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 커널 수정 없이 안전한 샌드박스 환경에서 커널 레벨 패킷을 처리하는 기술임 |
| 배경 | iptables 등 기존 네트워크 스택의 성능 한계 및 확장성 제약 극복 필요 |
| 출제 | CNI 성능 개선, 커널 네트워킹, XDP(eXpress Data Path), Cilium 연동 |

## Ⅱ. 구성요소
```text
+--------------+       +--------------+       +--------------+
| eBPF Program | ----> | eBPF Verifier| ----> |  JIT Compiler|
| (User Space) |       | (Kernel)     |       |  (Execution) |
+--------------+       +--------------+       +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| eBPF 프로그램 | 네트워크 패킷 필터링 등을 정의한 사용자 바이트코드임 | 지시서 |
| 검증기 (Verifier) | 코드가 커널을 크래시시키지 않도록 안전성 사전 검증함 | 안전 검사관 |
| JIT 컴파일러 | 바이트코드를 머신 코드로 변환하여 고성능 커널 처리 수행함 | 실시간 번역기 |

> 요약: 사용자 정의 프로그램을 커널 내 검증 및 컴파일을 거쳐 안전 실행함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Coding | -> | 2. Compile| -> | 3. Load   | -> | 4. Attach |
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 코드 작성 (Coding): C언어 등으로 네트워크 패킷 처리 로직 작성함.
2. 컴파일 (Compile): LLVM/Clang 도구를 통해 eBPF 바이트코드로 변환함.
3. 적재 (Load): bpf() 시스템 콜을 호출하여 커널 공간으로 코드 로드함.
4. 부착 (Attach): XDP, TC 등 지정된 네트워크 훅에 프로그램을 부착함.

> 요약: 프로그램 작성 후 바이트코드로 변환하여 커널 네트워크 훅에 결합함.

## Ⅳ. 문제점
- 학습 곡선: C언어 및 리눅스 커널 구조에 대한 깊은 이해가 요구됨.
- 디버깅: 커널 레벨 동작으로 인해 트러블슈팅 및 가시성 확보 까다로움.
- 호환성: 구버전 리눅스 커널에서는 eBPF의 최신 고성능 기능 지원 불가함.

## Ⅴ. 개선방안
- 고수준 프레임워크 (단기): Cilium 등 eBPF 기반 추상화 툴을 적극 도입함.
- 전용 모니터링 (중기): Hubble과 같은 eBPF 전용 옵저버빌리티 시스템 구축함.
- 커널 업그레이드 (장기): 인프라 커널 버전을 최신으로 유지하여 호환성 확보함.

## Ⅵ. 전망
- eBPF는 클라우드 네이티브 네트워크 데이터 평면의 표준이 되며 SmartNIC 기반 하드웨어 오프로딩과 융합될 것임.
