## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 단말기가 사내 네트워크에 접근하기 전, 보안 정책 준수 여부(무결성)를 검사하여 인가된 기기만 접속을 허용하는 통합 보안 솔루션 |
| **배경/필요성** | BYOD(Bring Your Own Device) 확산에 따른 비인가 무선 공유기, 악성코드 감염 PC의 내부망 접속 원천 차단 필요 |
| **출제 의도** | 사전 인증 체계, 상태 검사(Posture Assessment), VLAN 격리 메커니즘을 통한 무결성 보장 기능 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Client  |       |   NAC    |       |   Auth   |
| (Agent)  | <---> | (Sensor) | <---> | (Server) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Policy Server | 보안 정책 수립, 단말 무결성 검증, 최종 접속 허용 여부를 결정하는 중앙 통제소 | 본사 보안 컨트롤타워 |
| Sensor (Enforcer) | 스위치 앞단에서 실제 트래픽을 차단하거나 격리(VLAN)하는 집행 장비 | 현장 출입문 경비원 |
| Agent (에이전트) | 단말에 설치되어 OS 패치, 백신 구동 상태 등을 수집하고 서버로 전송하는 소프트웨어 | 신원 및 건강 진단서 |

> 요약: 단말 무결성 검증과 802.1X/ARP 통제 기반의 강력한 차단 조치로 안전한 단말만 망 접속을 허용함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 망 접속  | -> | 무결성검사| -> | 격리/조치| -> | 최종 인가|
+----------+    +----------+    +----------+    +----------+
```
1. 망 접속: 단말(PC/스마트폰)이 스위치나 무선 AP를 통해 최초 물리적(또는 논리적) 연결 시도
2. 무결성검사: NAC 센서가 트래픽을 차단한 상태에서 에이전트(또는 에이전트리스)를 통해 백신/패치 상태 수집 및 평가
3. 격리/조치: 보안 기준 미달(악성 감염 등) 기기는 차단되거나 치료를 위한 제한된(Guest) VLAN으로 격리 조치
4. 최종 인가: 치료(Remediation) 완료 및 정책 준수 확인 시, 스위치 포트를 정상 업무 VLAN으로 변경 개방

> 요약: 단말 검증 결과에 따라 동적 VLAN 할당 및 포트 제어를 수행해 비인가 단말을 완벽 통제함

## Ⅳ. 문제점
- 사내 수많은 단말에 백그라운드 에이전트를 강제 설치해야 하므로 호환성 및 PC 성능 저하(오버헤드) 불만 가중
- Agent-less(비설치형) 방식 운용 시 단말의 세부 상태(레지스트리, 딥 검사) 확인 불가로 보안 검증 한계 노출
- 대규모 엔터프라이즈 환경에서 ARP 스푸핑 기반의 NAC 차단 방식 사용 시 스위치 부하 및 트래픽 폭주 장애 발생

## Ⅴ. 개선방안
- [단기] 사용자 불만 감소를 위해 직원 PC는 Agent 방식, IoT/게스트 기기는 Agent-less 방식으로 유연한 이중화 적용
- [중기] ARP 기반 차단을 탈피하고 802.1X(포트 기반) 표준 인증 프로토콜과 연동하여 스위치(L2) 레벨의 근본적 차단 구축
- [장기] 외부 위협 정보(CTI) 및 차세대 방화벽과 연동하여 감염 단말 발생 시 NAC가 실시간으로 포트를 내리는 자동 대응(SOAR) 구현

## Ⅵ. 전망
- 클라우드 및 재택근무가 표준화되며 경계형 NAC에서 제로 트러스트(ZTNA) 아키텍처 기반의 상시 검증 모델로 진화할 전망임
