## 미리 알고가기

- 라우팅: 목적지 IP 주소에 맞는 다음 홉과 출력 인터페이스를 정하는 과정임
- 라우팅 테이블: 목적지 프리픽스, 다음 홉, 인터페이스, 메트릭을 저장한 표임
- Longest Prefix Match: 여러 경로 중 가장 긴 프리픽스가 일치하는 경로를 우선하는 규칙임
- Administrative Distance: 서로 다른 경로 출처가 충돌할 때 우선순위를 정하는 신뢰도 값임
- Metric: 같은 라우팅 프로토콜 안에서 경로 비용을 비교하는 값임

## Ⅰ. 개요

- **정의/개념**: 라우팅은 라우터가 목적지 IP와 라우팅 테이블을 비교해 다음 홉을 선택하고 패킷을 해당 인터페이스로 전달하는 네트워크 계층 기능임
- **배경/필요성**: 네트워크가 여러 경로로 연결되면 목적지별 전달 방향과 장애 시 우회 방식을 정해야 하므로 경로 선택 기준이 필요함

## Ⅱ. 특징

- 라우터는 가장 구체적인 프리픽스가 일치하는 경로를 먼저 선택함
- 정적 라우팅은 관리자가 경로를 직접 넣어 예측 가능하지만 변경 대응이 수동임
- 동적 라우팅은 라우터끼리 경로 정보를 교환해 장애와 토폴로지 변경을 반영함
- 경로 선택은 속도가 아니라 프리픽스, 출처 신뢰도, 메트릭 순서로 판단함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정적 라우팅 | 동적 라우팅 |
|:---|:---|:---|
| 경로 생성 | 관리자가 목적지와 다음 홉을 직접 설정함 | 프로토콜이 인접 라우터와 정보를 교환해 계산함 |
| 변경 대응 | 장애나 회선 변경 시 수동 수정이 필요함 | 프로토콜 수렴 후 우회 경로를 반영함 |
| 운영 비용 | 제어 트래픽과 계산 부담이 거의 없음 | 업데이트 메시지와 경로 계산 부담이 있음 |
| 적합 조건 | 단일 출구, 소규모, 고정 경로 구간에 적합함 | 다중 경로, 대규모, 장애 우회가 필요한 구간에 적합함 |

> 요약: 정적 라우팅은 경로를 고정하는 방식이고, 동적 라우팅은 변경된 토폴로지를 반영해 경로를 다시 계산하는 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Destination Prefix | 어떤 목적지 주소 범위에 적용되는 경로인지 나타냄 |
| Next Hop | 패킷을 다음으로 넘길 인접 라우터 주소임 |
| Outgoing Interface | 패킷이 나갈 물리 또는 논리 인터페이스임 |
| AD와 Metric | 경로 출처와 비용을 비교해 최종 경로를 고르는 기준임 |

```text
+--------+      +--------+      +--------+
| Host A | ---> | Router | ---> | NextHop|
+--------+      +--------+      +--------+
                 LPM -> AD -> Metric
```

> 요약: 라우팅 테이블은 목적지 프리픽스와 다음 홉을 연결하고, 우선순위 규칙으로 하나의 경로를 선택함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 목적지확인 | --> | LPM선택  | --> | 우선순위판단 | --> | 포워딩   |
+----------+     +----------+     +----------+     +----------+
```

1. **목적지확인**: 패킷의 목적지 IP 주소를 읽음
2. **LPM선택**: 라우팅 테이블에서 가장 긴 프리픽스가 일치하는 경로를 찾음
3. **우선순위판단**: 경로가 여러 개이면 AD와 Metric 기준으로 최종 경로를 정함
4. **포워딩**: 선택한 다음 홉과 출력 인터페이스로 패킷을 전달함

## Ⅵ. 실무 적용 및 유의점

1. 지사처럼 단일 출구만 있는 구간은 기본 경로와 정적 라우팅이 단순하지만 회선 장애 시 단절될 수 있으므로 추적 기반 정적 경로나 백업 경로를 두고 경로 전환 로그로 확인함
2. 대규모 내부망은 OSPF 같은 동적 라우팅이 맞지만 영역 설계가 틀리면 수렴 범위가 커지므로 LSA 수, 수렴 시간, 라우팅 테이블 크기로 적정성을 확인함

## Ⅶ. 결론

라우팅 선택은 빠른 길이라는 표현보다 프리픽스 일치, 경로 출처, 메트릭, 장애 대응 절차로 설명해야 정확함.

## 작성 근거(검토용)

- 라우팅 설명은 추상적인 최적 경로 표현으로 흐르기 쉬워 LPM, AD, Metric의 실제 판단 순서를 앞에 둠
- 정적·동적 비교는 우열이 아니라 변경 대응과 운영 비용 차이로 작성함
- 결론은 속도가 아니라 경로 선택 절차를 회수함
