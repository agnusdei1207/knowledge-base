# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 라우팅은 라우터가 목적지 IP(004 참조)까지 패킷을 어느 다음 홉(Next-hop)으로 보낼지 결정하는 경로 선택 과정이며, 경로를 사람이 손으로 넣으면 정적(Static), 프로토콜이 자동 학습하면 동적(Dynamic) 라우팅임.
- **왜 필요한가**: 인터넷은 수많은 네트워크가 라우터로 연결된 그물망이라, 각 라우터가 목적지별 최적 출구를 알고 있어야 패킷이 길을 잃지 않고 전달됨.
- **핵심 직관**: 내비게이션과 같음. 정적 라우팅은 운전자가 늘 다니는 길을 외워 고정하는 것이고, 동적 라우팅은 실시간 교통정보로 막히면 우회로를 자동 재탐색하는 것임.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안(Ⅰ~Ⅵ·표)에 나오는 것들을 미리 풀어 둔 것임. 최상위 키워드는 **경로 결정(Static vs Dynamic)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 라우팅 테이블 | 목적지 대역별 다음 홉·출구 인터페이스 기록표 | 목적지별 갈림길 안내판 |
| Next-hop | 목적지로 가기 위해 넘길 바로 다음 라우터 | 다음 갈림길까지의 방향 |
| 정적 라우팅 | 관리자가 경로를 수동 입력해 고정 | 외워 둔 고정 출퇴근 길 |
| 동적 라우팅 | 프로토콜이 이웃과 정보 교환해 자동 학습 | 실시간 교통정보 반영 |
| Default Route | 테이블에 없는 목적지의 기본 출구(0.0.0.0/0) | 모르면 일단 큰길로 |
| Metric | 경로의 좋고 나쁨을 나타내는 비용값 | 거리·소요시간 점수 |
| Convergence | 망 변화 후 모든 라우터 경로가 일치하는 상태 | 우회로 정보가 전체 공유된 시점 |
| AD(관리거리) | 여러 프로토콜 경로 중 우선순위(낮을수록 우선) | 정보원 신뢰도 순위 |
| Distance Vector | 이웃이 알려준 거리(홉)로 경로 결정(RIP) | 옆 사람 말만 듣고 판단 |
| Link State | 전체 지도를 공유해 최단경로 계산(OSPF) | 지도 전체를 보고 판단 |
| Path Vector | AS 경로를 정책으로 선택(BGP) | 통과 국가 목록으로 판단 |
| Longest Prefix Match | 가장 구체적(긴 마스크) 경로 우선 선택 규칙 | 더 상세한 주소가 우선 |

## 깊이 이해
- **배경·문제의식**: 초기 소규모 망은 경로를 손으로 넣어도 됐으나, 망이 커지고 회선 장애가 잦아지자 사람이 매번 경로를 고칠 수 없어 자동으로 경로를 학습·복구하는 동적 라우팅이 필요해짐.
- **작동 원리(어떻게+왜)**: 라우터는 수신 패킷의 목적지 IP를 라우팅 테이블에서 조회해 Longest Prefix Match로 가장 구체적인 경로의 Next-hop으로 전달함. 정적은 이 테이블을 사람이 채우고, 동적은 프로토콜(RIP·OSPF·BGP)이 이웃과 정보를 교환해 채우며 장애 시 자동으로 우회 경로를 재계산(Convergence)함. 같은 목적지를 여러 프로토콜이 알면 AD(관리거리)가 낮은 경로를 채택함.
- **비유**: 정적은 붙박이 도로 표지판이고, 동적은 서로 통신하는 스마트 내비게이션이 사고 소식을 공유해 우회로를 실시간 갱신하는 것과 같음.
- **구체 예시**: 지사 1개가 본사와 단일 회선으로만 연결되면 정적 경로 한 줄로 충분함. 반면 데이터센터처럼 경로가 수백 개고 이중화되면 OSPF(013 참조)가 장애를 수초 내 감지해 우회함.
- **흔한 오해·주의점**: 동적 라우팅이 항상 우월한 게 아님. CPU·대역폭을 쓰고 오설정 시 라우팅 루프 위험이 있어, 단순·안정 구간은 정적이 더 견고함.

## 연결 개념
- OSPF (013 참조) — 대표적 링크 상태(Link State) 동적 라우팅 프로토콜.
- RIP·거리 벡터 (014 참조) — 홉 수 기반의 단순 동적 라우팅.
- BGP (015 참조) — AS 간 정책 기반 경로 결정(Path Vector) 프로토콜.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 라우팅은 목적지 IP를 라우팅 테이블에서 Longest Prefix Match로 조회해 Next-hop을 결정하는 경로 선택 과정임.
> 2. **가치**: 정적은 예측 가능·저부하, 동적은 장애 시 자동 우회(Convergence)로, 망 규모·변동성에 따라 경로 관리 방식을 선택함.
> 3. **판단**: 소규모·단일 경로는 정적이 견고하나, 대규모·이중화 망은 동적(OSPF·BGP)이 필수이며, 실무는 둘을 혼용(Default+동적)함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 경로 결정 원리 | 라우팅 테이블·Longest Prefix Match·AD | 스위칭(L2 MAC 학습)과 라우팅 혼동 |
| 정적·동적 구분 | 수동 고정 vs 프로토콜 자동 학습·수렴 | 동적이 항상 우월하다는 단정 |
| 실무 적용 판단 | 규모·이중화별 선택과 혼용 설계 | 프로토콜 나열만 하고 선택 기준 누락 |

> 요약: 라우팅은 '테이블 조회 원리'로 경로 결정을 증명하고, 정적 vs 동적 트레이드오프와 혼용 설계로 결론지어야 함.

## Ⅰ. 개요 및 필요성

- 정의: 목적지 IP까지 패킷을 전달할 Next-hop을 라우팅 테이블 기반으로 선택하는 L3 경로 결정 과정임.
- 배경: 망이 그물망으로 커지고 장애가 잦아 수동 경로만으로는 복구·확장이 불가함.
- 필요성: 규모·변동성에 맞춰 정적(고정)·동적(자동 학습)을 선택·혼용해 도달성과 가용성을 확보함.

---

## Ⅱ. 구조 및 구성요소

구조도(선형):

```text
수신 패킷(목적지 IP) -> 라우터
  라우팅 테이블 조회 -> Longest Prefix Match로 최적 경로 선택
    경로 출처: 정적(수동 입력) / 동적(RIP·OSPF·BGP 학습)
    다중 출처 충돌 시 -> AD(관리거리) 낮은 경로 채택
  -> Next-hop 인터페이스로 전달 -> 다음 라우터 (없으면 Default Route)
```

| 구성요소 | 역할 | 특징 |
|:---|:---|:---|
| 라우팅 테이블 | 목적지 대역별 Next-hop 보유 | Longest Prefix Match로 조회 |
| 정적 경로 | 관리자 수동 입력 경로 | AD=1, 변동 없음 |
| 동적 프로토콜 | 이웃과 정보 교환해 경로 학습 | RIP·OSPF·BGP, 자동 수렴 |
| Default Route | 미등록 목적지의 기본 출구 | 0.0.0.0/0, 상위 망 위임 |

> 요약: 라우터는 테이블을 Longest Prefix Match로 조회하며, 정적·동적 출처가 겹치면 AD로 우선순위를 정함.

---

## Ⅲ. 동작원리 및 흐름도

흐름도(선형):

```text
목적지 IP 확인 -> 라우팅 테이블에서 매칭 경로 검색
  -> 여러 매칭 시 가장 긴 프리픽스(Longest Prefix Match) 선택
  -> 같은 목적지 다중 프로토콜이면 AD 낮은 경로 채택
  -> Next-hop으로 포워딩 / 매칭 없으면 Default Route
```

- 1단계: 라우터가 수신 패킷의 목적지 IP를 추출함.
- 2단계: 라우터가 라우팅 테이블에서 목적지와 매칭되는 경로를 검색함.
- 3단계: 라우터가 여러 매칭 중 가장 구체적인(마스크가 긴) 경로를 선택하고, 프로토콜이 겹치면 AD가 낮은 것을 채택함.
- 4단계: 라우터가 선택 경로의 Next-hop 인터페이스로 패킷을 전달하며, 동적 환경에서 링크 장애가 나면 프로토콜이 경로를 재계산해 수렴(Convergence)함.

> 요약: 라우터는 목적지 IP를 Longest Prefix Match로 조회해 Next-hop을 정하고, 동적 프로토콜은 장애 시 우회 경로로 자동 수렴함.

---

## Ⅳ. 특징

- 정적 라우팅의 예측성: 경로가 고정이라 CPU·대역폭 부담이 없고 동작이 결정적이나, 링크 장애 시 자동 우회가 없어 수동 복구가 필요함.
- 동적 라우팅의 자율 복구: 프로토콜이 이웃과 정보를 교환해 장애를 감지·우회하나, 제어 트래픽·CPU를 소모하고 수렴 지연 동안 일시적 루프·블랙홀이 생길 수 있음.
- AD 기반 우선순위: 같은 목적지를 정적·OSPF·BGP가 동시에 알면 AD(정적 1, OSPF 110, RIP 120 등)가 낮은 경로를 우선 채택함.
- 혼용 설계: 단말망 출구는 Default+정적으로 단순화하고, 코어·이중화 구간만 동적으로 두어 부하와 복구성을 함께 확보함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 정적 라우팅(Static) | 동적 라우팅(Dynamic) |
|:---|:---|:---|
| 경로 설정 | 관리자 수동 입력 | 프로토콜 자동 학습 |
| 장애 대응 | 수동 재설정 필요 | 자동 우회·수렴 |
| 자원 소모 | CPU·대역폭 부담 없음 | 제어 트래픽·CPU 소모 |
| 확장성 | 대수 늘면 관리 폭증 | 대규모 망에 적합 |
| 적용 구간 | 소규모·단일 경로·스텁망 | 대규모·이중화·코어망 |

> 요약: 예측성·저부하가 중요한 단순 구간은 정적을, 자동 복구·확장성이 필요한 대규모 이중화 구간은 동적을 적용하는 것이 원칙임.

리스크·대응(불릿):
- 라우팅 루프 — 동적 오설정·수렴 지연 — Split Horizon·Route Poisoning, OSPF는 SPF로 루프프리 보장.
- 정적 경로 블랙홀 — 링크 다운 후에도 경로 잔존 — IP SLA·Object Tracking으로 Next-hop 감시.
- 경로 오학습 — 신뢰 못 할 이웃의 경로 주입 — 인증(OSPF/BGP MD5)·Route Filtering 적용.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **스텁망 정적+Default**: 단일 회선 지사는 본사행 정적 경로와 Default Route 한 줄로 구성해 부하 없이 단순 운용.
2. **캠퍼스 코어 OSPF**: 이중화된 캠퍼스·데이터센터 내부는 OSPF(013 참조)로 Area를 나눠 수초 내 장애 우회를 확보.
3. **대외 연동 BGP**: ISP·멀티클라우드 등 AS 간 연결은 BGP(015 참조)로 정책 기반 경로를 제어하고 AS-Path Filtering으로 오경로를 차단.

**결론(2줄):**
- 기술사 판단: 소규모·단순 구간이면 정적으로 견고성을, 대규모·이중화 구간이면 동적으로 복구성을 확보하고 둘을 혼용해야 함.
- 향후 방향: SDN(066 참조) 환경에서는 컨트롤러가 중앙에서 경로를 계산·주입해, 분산 라우팅 프로토콜과 중앙 집중 제어가 병존하는 방향으로 진화함.
