# 📖 【암기용】 개념 완전 이해

> 목적: 라우팅을 처음 봐도 패킷이 어떤 기준으로 다음 홉을 선택하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 목적지 IP까지 갈 다음 홉과 인터페이스를 선택하는 네트워크 경로 결정 기능
- **왜 필요한가**: IP 패킷은 목적지 네트워크가 직접 연결되어 있지 않으면 라우터를 거쳐야 한다. 라우팅은 네트워크 장애, 비용, 관리 범위에 맞춰 경로를 선택한다.
- **핵심 직관**: 내비게이션이 목적지까지 어느 도로를 탈지 고르는 것처럼, 라우터는 라우팅 테이블에서 최장 prefix 일치 경로를 찾는다.

## 깊이 이해
- **배경·문제의식**: 소규모망은 관리자가 직접 경로를 넣는 정적 라우팅으로 충분하다. 대규모망은 링크 장애와 신규 경로를 사람이 즉시 반영하기 어렵기 때문에 OSPF, RIP, BGP 같은 동적 라우팅이 필요하다.
- **작동 원리**: 라우터는 목적지 IP와 라우팅 테이블 prefix를 비교해 가장 긴 prefix를 선택한다. 동일 prefix가 여러 개면 AD(Administrative Distance), metric, ECMP 정책을 기준으로 결정한다.
- **비유**: 정적 라우팅은 종이에 직접 그린 고정 약도이고, 동적 라우팅은 교통 상황을 반영하는 내비게이션이다.
- **구체 예시**: `0.0.0.0/0 -> 192.0.2.1`은 기본 경로, `10.10.0.0/16 -> 10.1.1.2`는 특정 내부망 경로다. `/16`은 `/0`보다 길어 우선 선택된다.
- **흔한 오해·주의점**: 동적 라우팅이 항상 정적 라우팅을 대체하지 않는다. 기본 경로, 소규모 지점, 보안 분리 구간은 정적 라우팅이 운영 통제에 적합하다.

## 연결 개념
- OSPF — 링크 상태 기반 IGP, cost로 내부 경로 계산
- BGP — AS 간 정책 라우팅, AS_PATH와 LOCAL_PREF 활용
- CIDR — prefix 길이가 라우팅 테이블 집약과 최장 prefix 매칭 기준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 정적·동적 라우팅은 단순 경로 입력 방식 차이가 아니라 장애 수렴, 운영 통제, 라우팅 루프 방지 관점으로 비교한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 라우팅은 목적지 IP prefix에 대해 다음 홉, 출력 인터페이스, metric을 선택하는 L3 경로 결정 기능이다.
> 2. **가치**: 정적 라우팅은 통제 범위를 좁히고, 동적 라우팅은 장애·증설 시 경로 정보를 프로토콜로 갱신한다.
> 3. **판단 포인트**: 규모, 변경 빈도, convergence time, AD, metric, route summarization, 루프 방지 기법을 기준으로 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 라우팅 기본 원리 확인 | 최장 prefix, next-hop, AD, metric | 라우팅과 스위칭 혼동 |
| 정적·동적 비교 역량 확인 | 관리 부담, 장애 수렴, 프로토콜 오버헤드 | 동적 라우팅을 무조건 우선으로 서술 |
| 운영 설계 판단 확인 | 기본 경로, 재분배, 요약, 루프 방지 | route redistribution 리스크 누락 |

> 요약: 라우팅 문제는 경로 선택 순서와 정적·동적 선택 기준을 수렴 시간과 운영 통제 관점으로 써야 한다.

## Ⅰ. 개요 및 필요성

- 정의: IP 패킷의 목적지까지 다음 홉을 결정하는 L3 경로 선택 기능
- 배경: 네트워크가 여러 세그먼트·AS로 분할되면 라우터가 경로 정보 기준으로 패킷을 전달해야 함
- 필요성: 정적 라우팅은 관리자가 수동 입력하고, 동적 라우팅은 프로토콜이 상태 변화를 자동 반영함

---

## Ⅱ. 구조 및 구성요소

```text
Destination IP -> Longest Prefix Match -> Route Selection
  / Static Route
  / Dynamic Route Protocol
  / AD and Metric
Selected Route -> Next-Hop -> Output Interface
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 라우팅 테이블 | 목적지 prefix와 next-hop 저장 | connected, static, dynamic 포함 |
| 최장 prefix 매칭 | 목적지 IP와 가장 긴 prefix 선택 | /24가 /16보다 우선 |
| AD | 경로 출처 신뢰도 판단 | Cisco 예: connected 0, static 1 |
| Metric | 동일 프로토콜 내 경로 비용 | hop count, cost, bandwidth 등 |

> 요약: 라우팅 구조는 최장 prefix를 먼저 찾고, 경합 시 AD와 metric으로 다음 홉을 확정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Packet Receive -> Destination Prefix Lookup -> Longest Match
  -> AD Compare -> Metric Compare -> Next-Hop Resolve
  -> TTL Decrement -> Forward or Drop
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목적지 IP로 라우팅 테이블 조회 | longest prefix match |
| 2 | 복수 경로가 있으면 AD 비교 | lower AD selected |
| 3 | 동일 프로토콜 경로는 metric 비교 | OSPF cost, RIP hop count |
| 4 | TTL을 1만큼 감소시킨 후 출력 인터페이스로 전달 | TTL 0이면 ICMP Time Exceeded |

> 요약: 라우터는 prefix, AD, metric, TTL 처리 순서로 L3 패킷 전달 여부를 결정한다.

---

## Ⅳ. 특징

| 구분 | 정적 라우팅 | 동적 라우팅 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 경로 생성 | 관리자가 수동 입력 | OSPF, RIP, BGP 등이 광고 | AD, metric 사용 |
| 장애 반영 | 수동 변경 또는 tracking 필요 | hello/dead timer로 감지 | OSPF dead interval 기본 40초 |
| 운영 범위 | 소규모 지점, default route | 대규모·다중 경로 | ECMP, summarization |
| 위험 | 설정 누락, next-hop 장애 | 루프, 재분배 오류 | TTL, split horizon |

> 요약: 정적 라우팅은 통제성, 동적 라우팅은 장애 수렴과 규모 대응이 선택 기준이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정적 라우팅 | 동적 라우팅 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 경로 수동 고정 | 라우팅 프로토콜로 경로 교환 | 경로 변경 월 1회 이하는 정적 우선 |
| 비용/성능 | CPU·메모리 사용량 낮음 | hello, LSA, update 오버헤드 | 장비 CPU 70% 이하 유지 |
| 운영/위험 | 변경 승인 추적 쉬움 | convergence time 관리 필요 | 장애 감지 목표 1분 이내 |

> 요약: 네트워크 규모와 장애 수렴 목표가 정적·동적 라우팅 선택의 핵심 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 블랙홀 | next-hop 장애 후 정적 경로 유지 | IP SLA tracking, BFD | drop packet count |
| 루프 | 재분배 정책 오류 | route-map, tag, summarization | traceroute 반복 hop |
| 수렴 지연 | hello/dead timer 과대 | BFD 300ms, timer 조정 | convergence time |

> 요약: 라우팅 리스크는 블랙홀, 루프, 수렴 지연이며 추적·태깅·BFD로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 경로 정확성 | 핵심 prefix 100% 등록 | route table audit |
| 수렴 시간 | 내부망 30초~60초 이내 | link down test |
| 루프 방지 | 동일 prefix 재유입 0건 | routing log, traceroute |

> 요약: 라우팅 운영 품질은 경로 정확성, 수렴 시간, 루프 방지 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 소규모 지점과 인터넷 기본 경로는 정적 `0.0.0.0/0`과 IP SLA tracking을 적용해 블랙홀 시간을 줄임
2. 본사·데이터센터 내부는 OSPF area 설계와 summarization으로 LSA 범위를 제한함
3. 정적·동적 재분배 구간은 route-map, prefix-list, tag로 재유입 루프를 차단함

**결론 (2줄):**
- 기술사 판단: 변경 빈도가 낮고 경로 수가 적으면 정적, 장애 자동 수렴과 다중 경로가 필요하면 동적 라우팅을 선택함
- 향후 방향: BFD, telemetry, intent 기반 정책 검증으로 라우팅 변경 전후의 수렴성과 루프 여부를 자동 점검해야 함
