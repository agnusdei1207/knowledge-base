# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 패킷이 목적지까지 가는 최적의 경로를 결정하고, 그 경로를 따라 패킷을 전달(Forwarding)하는 과정입니다.
- **필요성**: 복잡한 거미줄 같은 네트워크에서 패킷이 길을 잃지 않고 가장 빠르고 안전하게 도착하려면, 중간 정거장(라우터)마다 올바른 방향을 지시해줘야 합니다.
- **핵심 직관**: **"디지털 내비게이션"**. 사람이 직접 길을 정해주면 **정적(Static)**, 내비게이션이 알아서 길을 찾으면 **동적(Dynamic)** 라우팅입니다.

## 깊이 이해
- **배경 (왜 두 가지 방식인가?)**: 초기 네트워크는 단순해서 사람이 직접 길을 알려줘도 충분했습니다. 하지만 인터넷 규모가 커지고 회선 장애가 잦아지면서, 장애가 나면 스스로 우회로를 찾는 '지능형' 라우팅 프로토콜이 필요해졌습니다.
- **작동 원리 (경로 결정의 기준)**:
  - **정적 라우팅**: 관리자가 `ip route 1.1.1.0 255.255.255.0 2.2.2.1` 처럼 직접 입력합니다. 변하지 않으므로 안정적이고 라우터의 부하가 없습니다.
  - **동적 라우팅**: 라우터끼리 "내 주변엔 이런 네트워크가 있어"라고 정보를 주고받으며 **라우팅 테이블**을 자동으로 만듭니다.
  - **AD (Administrative Distance)**: 여러 정보원(RIP, OSPF 등)이 다른 길을 알려줄 때, 누구의 말을 더 믿을지 결정하는 '신뢰도' 점수입니다. (낮을수록 우선)
- **비유 (출근길 선택)**:
  - **정적**: 매일 똑같은 길로만 가는 것. 사고가 나서 막혀도(장애) 계속 그 길로 가려 함.
  - **동적**: T맵을 켜고 가는 것. 사고가 나면 실시간으로 우회로(Convergence)를 알려줌.

## 연결 개념
- **Default Route**: "모르는 주소면 일단 이쪽으로 보내!"라고 정해둔 기본 출구. (0.0.0.0/0)
- **Convergence Time**: 네트워크에 변화가 생겼을 때, 모든 라우터가 새로운 경로 정보를 공유하고 일치하기까지 걸리는 시간.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 목적지 IP 주소를 기반으로 최적 경로(Best Path)를 선출하여 라우팅 테이블에 등록하고 패킷을 전송하는 L3 핵심 메커니즘임.
> 2. **가치**: 정적 라우팅은 '관리 효율성'과 '예측 가능성'을, 동적 라우팅은 '자용성'과 '자동화된 장애 복구'를 제공함.
> 3. **판단 포인트**: 네트워크의 규모와 복잡도에 따라 정적(Stub망), OSPF(내부망), BGP(대외망)를 적재적소에 혼합 설계(Redistribution)해야 함.

## Ⅰ. 라우팅(Routing)의 정의 및 경로 결정 원칙
- **정의**: 라우터가 수신한 패킷의 목적지 IP 주소를 확인하여 최적의 경로를 결정하고 해당 인터페이스로 패킷을 전달하는 프로세스.
- **경로 선출 원칙 (Priority)**:
  1. **Longest Prefix Match**: 서브넷 마스크가 가장 길게(상세하게) 일치하는 경로 우선.
  2. **Administrative Distance (AD)**: 경로 정보의 출처(프로토콜)별 신뢰도 순위 적용.
  3. **Metric**: 동일 프로토콜 내에서 비용(Cost, Hop 등)이 가장 낮은 경로 선택.

## Ⅱ. 정적 라우팅 vs 동적 라우팅 비교 분석

| 비교 항목 | 정적 라우팅 (Static) | 동적 라우팅 (Dynamic) |
|:---:|:---|:---|
| **경로 설정** | 관리자가 수동으로 경로 입력 | 프로토콜이 인접 라우터와 정보 교환 |
| **장애 대응** | 우회 경로 자동 생성 불가 (수동 개입) | 장애 발생 시 자동 우회 경로 산출 |
| **자원 소모** | CPU/메모리 부하 거의 없음 | 연산 및 업데이트 패킷 발생 (부하 존재) |
| **수렴 속도** | 즉시 반영 (단, 수동 작업 지연) | 프로토콜 알고리즘에 따른 수렴 시간 소요 |
| **적용 규모** | 소규모, Stub Network (단일 출구) | 대규모, 복잡한 메쉬 구조 네트워크 |

## Ⅲ. 동적 라우팅 프로토콜의 알고리즘별 분류

### 1. Distance Vector (거리 벡터)
- **특징**: 벨만-포드(Bellman-Ford) 알고리즘 기반. 인접 라우터와 거리(Hop Count) 정보만 교환.
- **대표**: RIP, IGRP.
- **한계**: 루프(Loop) 발생 가능성, 느린 수렴 속도.

### 2. Link State (링크 상태)
- **특징**: 다익스트라(Dijkstra) 알고리즘 기반. 전체 네트워크 지도를 그리고 최단 경로 계산.
- **대표**: OSPF, IS-IS.
- **장점**: 빠른 수렴, 계층적 구조를 통한 대규모 망 지원.

### 3. Path Vector (경로 벡터)
- **특징**: AS(Autonomous System) 단위의 경로 정보를 전달. 정책 기반 라우팅.
- **대표**: BGP (인터넷 라우팅의 핵심).

## Ⅳ. 라우팅 테이블 관리 및 주요 파라미터

### 1. AD (Administrative Distance) 주요 값
- Connected: 0 / Static: 1 / EIGRP: 90 / OSPF: 110 / RIP: 120.
### 2. Default Route (기본 경로)
- 목적지가 라우팅 테이블에 없을 때 패킷을 보낼 마지막 수단 (`0.0.0.0 0.0.0.0`).
- 인터넷으로 나가는 관문 라우터나 말단 지사 라우터에 필수적.

## Ⅴ. 실무적 라우팅 설계 전략

### 1. 계층적 라우팅 (Hierarchical Routing)
- Core/Distribution/Access 계층별로 라우팅 영역을 분리하여 업데이트 범위를 제한.
### 2. 경로 재분배 (Redistribution)
- 서로 다른 라우팅 프로토콜(예: Static <-> OSPF) 간에 경로 정보를 상호 교환하여 전체 도달성 확보.
### 3. 부하 분산 (Load Balancing)
- **ECMP (Equal Cost Multi-Path)**: 동일한 비용의 여러 경로가 있을 때 트래픽을 분산 전송.

## Ⅵ. 기술사적 통찰: '안정'과 '유연'의 조화
- **정적 라우팅의 미학**: 최신 기술이 좋다고 모든 곳에 동적 라우팅을 쓰는 것은 낭비임. 변경이 없는 구간이나 보안이 중요한 구간은 정적 라우팅이 가장 강력한 통제 수단이 됨.
- **SDN/IBN의 파동**: 소프트웨어 정의 네트워크(SDN)에서는 라우터가 각자 계산하던 경로를 중앙 컨트롤러가 일괄 계산하여 주입함. 이는 분산형 동적 라우팅의 한계를 중앙의 가시성으로 극복하는 진화임.
- **결론**: 라우팅 설계는 단순히 연결하는 것이 아니라, 장애 시나리오를 예측하고 관리 복잡도를 최적화하는 **"네트워크의 신경망 설계"**임.
