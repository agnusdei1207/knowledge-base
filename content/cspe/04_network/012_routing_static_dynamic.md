# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 목적지 네트워크로 가는 최적의 경로를 설정하는 방법(수동 설정 vs 자동 학습)
- **왜 필요한가**: 수많은 네트워크 장비 사이에서 패킷이 헤매지 않고 목적지에 도달하려면 네비게이션(라우팅 테이블)이 필요함
- **핵심 직관**: 정적 라우팅은 '종이 지도'처럼 사람이 직접 경로를 그려주는 것이고, 동적 라우팅은 '실시간 내비게이션'처럼 막히는 길을 우회해 자동으로 경로를 찾는 것이다.

## 깊이 이해
- **배경·문제의식**: 소규모 망에서는 관리자가 경로를 수동 입력(Static)해도 되지만, 망이 커지면 링크 다운이나 경로 변경 시 수동 업데이트가 불가능해짐. 라우터끼리 통신해 경로를 자동 업데이트(Dynamic)하는 기술이 필요해짐.
- **작동 원리**: 
  - 정적: 관리자가 `ip route [목적지] [넥스트홉]` 명령어로 라우팅 테이블에 하드코딩함.
  - 동적: 라우팅 프로토콜(OSPF, BGP 등)이 주기적으로 라우팅 업데이트 메시지를 교환하여, 최단 경로 알고리즘(Dijkstra, Bellman-Ford)으로 최적 경로를 계산해 테이블에 기록함.
- **비유**: 정적은 고정된 버스 노선도(안정적이나 유연성 부족). 동적은 택시 기사들의 무전 공유(사고 나면 즉각 우회도로 파악).
- **구체 예시**: 10대 규모의 지사 라우터는 디폴트 라우트(정적)로 본사만 바라보게 구성하고, 1,000대 규모의 본사 백본은 OSPF(동적)로 복잡한 경로를 자동 관리함.
- **흔한 오해·주의점**: 동적 라우팅이 무조건 좋은 것은 아님. 보안성이 낮고(위조된 라우팅 정보 수신 가능) 라우터 CPU/메모리 자원을 소모하므로 망 규모에 맞게 혼용(Redistribution)해야 함.

## 연결 개념
- 라우팅 테이블(Routing Table) 및 넥스트 홉(Next Hop)
- 최장 일치 규칙(Longest Prefix Match)
- 관리 거리(Administrative Distance, AD)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 라우팅 테이블 생성 주체(관리자 수동 입력 vs 라우팅 프로토콜 자동 계산)에 따른 분류
> 2. **가치**: 네트워크 토폴로지 규모와 요구 보안성/안정성에 맞춘 최적의 경로 제어 방식 제공
> 3. **판단 포인트**: 정적 라우팅의 관리 오버헤드와 동적 라우팅의 자원 소모/토폴로지 수렴 시간(Convergence Time) 트레이드오프

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 망 규모에 따른 라우팅 방식 선택 및 비교 | 토폴로지 변화에 따른 수렴(Convergence) 처리 방식, AD 값 우선순위 | 정적 라우팅을 구식 기술로 폄하 (디폴트 라우팅 등 필수 요소임) |

> 요약: 망 변경에 대한 대응 방식과 관리 부하 측면에서 정적 라우팅과 동적 라우팅을 객관적 지표로 비교해야 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 패킷을 목적지까지 전달하기 위해 라우팅 테이블을 구성·유지하는 경로 설정 방식
- 배경: 망 규모 확대와 링크 장애 빈도 증가로 수동 경로 제어의 한계 도달
- 필요성: 환경(Stub Network vs Backbone)에 적합한 경로 제어를 통해 패킷 손실 최소화 및 대역폭 최적화

---

## Ⅱ. 구조 및 구성요소

```text
[라우팅 소스] ----> [라우팅 프로세스] ----> [라우팅 테이블 (RIB)] ----> [포워딩 테이블 (FIB)]
관리자 입력 (Static)       | AD 비교 / 최적 경로 선정        |               | 패킷 스위칭
라우팅 프로토콜 (Dynamic)  +-> 매트릭 연산                  +-> 목적지/인터페이스 매핑
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 라우팅 소스 | 경로 정보를 제공하는 주체(Static, RIP, OSPF, BGP) | 프로토콜별 Metric 산출 방식 상이 |
| AD (Administrative Distance) | 서로 다른 라우팅 소스 간의 신뢰도 우선순위 값 | 낮을수록 우선 (Static:1, OSPF:110) |
| 라우팅 테이블 (RIB) | 컨트롤 플레인(Control Plane)의 전체 경로 데이터베이스 | 최적 경로만 저장 |
| 포워딩 테이블 (FIB) | 데이터 플레인(Data Plane)의 고속 패킷 스위칭용 캐시 테이블 | 하드웨어(TCAM)에 저장 |

> 요약: 다양한 방식(Static/Dynamic)으로 수집된 경로 중 AD와 Metric이 가장 우수한 경로가 포워딩 테이블로 내려감.

---

## Ⅲ. 동작원리 및 흐름도

```text
링크 상태 변화 -> 라우터 인지 -> 테이블 업데이트(Dynamic) / 수동 변경(Static) -> 새 경로로 패킷 포워딩
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 토폴로지 변화 발생 (링크 다운) | 포트 상태 확인 (Up/Down) |
| 2 | 변화 인지 및 전파 | 동적: 헬로 패킷 누락 감지 / 정적: 관리자 개입 |
| 3 | 최적 경로 재계산 | 대체 경로(Backup Route) 산출 알고리즘 |
| 4 | 라우팅/포워딩 테이블 갱신 | 수렴 시간(Convergence Time) 최소화 |

> 요약: 링크 상태 변화 시, 동적 라우팅은 알고리즘에 의해 자동 수렴하고 정적 라우팅은 관리자의 수동 업데이트에 의존함.

---

## Ⅳ. 특징

| 구분 | 정적 라우팅 (Static) | 동적 라우팅 (Dynamic) | 판단 포인트 |
|:---|:---|:---|:---|
| 경로 갱신 | 관리자 수동 개입 (링크 다운 시 즉시 반영 불가) | 라우팅 프로토콜 자동 갱신 (수렴 시간 소요) | 가용성 및 장애 대응 속도 |
| 대역폭 소모 | 없음 (경로 교환 메시지 없음) | 발생 (Hello 메시지, LSA 업데이트 등 교환) | WAN 링크 트래픽 부담 |
| 자원 사용률 | 라우터 CPU/메모리 부하 최소 | 알고리즘 연산(Dijkstra) 및 DB 유지로 부하 높음 | 저사양 엣지 라우터 적용 여부 |

> 요약: 정적 라우팅은 자원 소모가 없으나 장애 대응이 취약하고, 동적 라우팅은 자원을 소모하며 장애에 유연함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정적 라우팅 | 동적 라우팅 (IGP - OSPF 등) | 선택 기준 |
|:---|:---|:---|:---|
| 보안성 | 외부 경로 주입(Route Injection) 공격 원천 차단 | 인증 미설정 시 위조된 경로 수신 리스크 존재 | 폐쇄망/DMZ 접근 제어 |
| 네트워크 규모 | 소규모 / Stub 네트워크 / Hub & Spoke | 중/대규모 토폴로지 / Mesh 네트워크 | 노드 수 및 경로 복잡도 |
| 장애 허용(Fault Tolerance)| 대체 경로 수동 절체 (Floating Static 제외) | 자동 우회 (Fast Convergence) | SLA 무중단 요구사항 |

> 요약: 보안과 단일 경로 구조가 중요하면 정적 라우팅, 복잡한 토폴로지와 장애 우회가 중요하면 동적 라우팅을 채택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 라우팅 블랙홀 (Static) | 목적지 장비 다운에도 정적 경로가 계속 살아있음 | BFD(Bidirectional Forwarding Detection) 연동, IP SLA | 경로 장애 감지 시간(ms) |
| 라우팅 루프 (Dynamic) | 경로 정보 불일치 및 전파 지연으로 패킷 무한 순환 | 스플릿 호라이즌(Split Horizon), 포이즌 리버스(Poison Reverse) | TTL 만료 패킷 수, CPU 사용률 |
| 잘못된 경로 주입 | 내부자 또는 악의적 노드의 거짓 정보(LSA) 유포 | 라우팅 프로토콜 인증(MD5, SHA-2) 적용 | 비정상 라우팅 업데이트 로그 |

> 요약: 정적 라우팅은 상태 기반 감지(BFD)로 한계를 보완하고, 동적 라우팅은 루프 방지와 메시지 인증을 필수로 적용해야 함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. [엣지 연동] 지사(Branch) 라우터는 복잡한 동적 라우팅 대신 본사 향 디폴트 정적 라우트(0.0.0.0/0) 단일 구성
2. [백업 경로] 플로팅 정적 라우팅(Floating Static Routing) 적용 시, 백업 링크의 AD 값을 동적 라우팅(OSPF:110)보다 높게(예: 120) 설정하여 평시 대기
3. [재분배] OSPF 도메인에서 외부 정적 라우트를 재분배(Redistribute Static)할 때, 특정 대역만 허용하는 Route-Map과 Prefix-List 필터링 적용

**결론 (2줄):**
- 기술사 판단: 단일 경로 및 보안이 중요한 구간은 정적 라우팅을, 가용성과 확장성이 요구되는 백본은 동적 라우팅을 분리 설계하는 하이브리드 방식이 필수적이다.
- 향후 방향: SDN/SD-WAN 환경에서는 컨트롤러가 중앙 집중식으로 동적 토폴로지를 분석하고 엣지에 정적 기반 정책 경로를 내리는 형태로 진화 중이다.
