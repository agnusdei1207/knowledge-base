## 미리 알고가기

- 애드혹 네트워크는 기지국이나 AP 없이 단말끼리 직접 연결하는 분산 무선망임
- 멀티홉은 중간 노드가 패킷을 대신 전달해 목적지까지 이어 주는 방식임
- AODV는 필요할 때만 경로를 찾는 요구 기반 라우팅 프로토콜임
- RREQ는 경로를 찾기 위해 뿌리는 요청 메시지이고 RREP는 찾은 경로를 되돌려 주는 응답 메시지임
- RERR는 기존 경로가 끊어졌음을 알리는 오류 메시지임

## Ⅰ. 개요

- **정의/개념**: 애드혹 네트워크는 중앙 인프라 없이 단말이 서로 중계해 통신하는 무선망이며, AODV는 이 환경에서 실제 통신이 필요해질 때만 경로를 탐색하고 유지하는 대표적인 라우팅 방식임
- **배경/필요성**: 재난 현장이나 임시 작전 구역에서는 단말 이동으로 경로가 자주 바뀌므로 모든 경로의 주기적 갱신 대신 통신 요청 시 경로를 탐색하는 방식이 필요함

## Ⅱ. 특징

- 중앙 장비 없이 단말이 중계 노드로 참여하여 임시 다중 홉 경로를 구성함
- AODV는 경로가 필요할 때만 탐색해 제어 트래픽과 배터리 소모를 줄임
- 이동성이 큰 환경에서는 경로 재탐색이 잦아질 수 있어 초기 전송 지연이 생길 수 있음
- 순차 번호를 이용해 오래된 경로와 라우팅 루프를 피함

## Ⅲ. 종류 및 비교

| 판단 기준 | Proactive 라우팅 | AODV 같은 Reactive 라우팅 |
|:---|:---|:---|
| 경로 유지 방식 | 통신 여부와 무관하게 경로 정보를 계속 갱신함 | 실제 데이터 전송이 필요할 때만 경로를 찾음 |
| 초기 전송 지연 | 이미 경로가 있어 첫 패킷 전송이 빠름 | 경로 탐색 시간이 있어 첫 패킷은 늦어질 수 있음 |
| 제어 오버헤드 | 이동이 많을수록 주기적 갱신 비용이 커짐 | 트래픽이 적을 때는 제어 비용을 크게 줄일 수 있음 |
| 적합한 환경 | 토폴로지가 비교적 안정된 무선망에 적합함 | 이동성과 단절이 잦은 현장형 무선망에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 노드 | 송신자이면서 동시에 중계자 역할을 수행할 수 있는 단말임 |
| 라우팅 테이블 | 현재 유효한 목적지 경로와 다음 홉과 순차 번호를 저장함 |
| RREQ | 목적지까지 가는 경로를 찾기 위해 주변으로 확산되는 요청 메시지임 |
| RREP | 목적지나 경로를 아는 노드가 되돌려 주는 응답 메시지이며 실제 데이터 경로를 확정함 |
| RERR | 중간 링크가 끊겼을 때 관련 노드에 경로 무효를 알리는 유지 관리 메시지임 |

```text
+--------+     +--------+     +--------+     +--------+
| 송신 노드 | --> | 중계 노드 | --> | 중계 노드 | --> | 목적지   |
+--------+     +--------+     +--------+     +--------+
    RREQ 확산         RREP 역방향 회신           데이터 전달
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 전송 요구 발생 | --> | RREQ 확산    | --> | RREP 회신    | --> | 데이터 전달   | --> | 경로 오류 복구 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **전송 요구 발생**: 송신 노드가 목적지 경로가 없음을 확인하면 탐색을 시작함
2. **RREQ 확산**: 주변 노드가 요청을 전달하며 목적지를 찾음
3. **RREP 회신**: 목적지나 유효 경로를 가진 노드가 반대 방향으로 응답을 보냄
4. **데이터 전달**: 확정된 다음 홉 정보를 따라 실제 데이터를 전송함
5. **경로 오류 복구**: 링크가 끊기면 RERR를 보내고 필요 시 다시 RREQ를 시작함

## Ⅵ. 실무 적용 및 유의점

1. 재난 대응이나 임시 행사망처럼 인프라 없이 빠르게 통신을 열어야 하는 환경에서는 AODV가 유용하지만 이동이 과하면 재탐색이 반복되므로 경로 탐색 지연, 제어 패킷 비율, 경로 단절 횟수로 안정성을 확인함
2. 노드 수가 많아지면 RREQ 확산 자체가 혼잡을 만들 수 있으므로 브로드캐스트 범위와 재시도 정책을 조정하고 채널 점유율, 배터리 소모, 패킷 성공률로 튜닝 결과를 확인함

## Ⅶ. 결론

AODV는 통신 요청 시 경로를 탐색하고 시퀀스 번호로 최신 경로를 구분하며 링크 단절 시 재탐색함.
