# 📖 【암기용】 개념 완전 이해

> 목적: Ad-hoc 네트워크와 AODV 라우팅을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 고정 인프라 없이 단말이 서로 라우터 역할을 수행하는 자율 무선망
- **왜 필요한가**: 재난 현장, 군 작전, 임시 센서망처럼 AP·기지국이 없거나 손상된 환경에서도 통신 경로가 필요함
- **핵심 직관**: 길을 모르면 전체 지도를 들고 다니지 않고, 목적지가 필요할 때 주변에 물어 경로를 찾는 방식임

## 깊이 이해
- **배경·문제의식**: 기존 무선 LAN은 AP 중심 구조라 AP 장애·전원 차단 시 통신이 중단됨. Ad-hoc은 단말 간 다중 홉으로 목적지까지 패킷을 중계함.
- **작동 원리**: AODV(Ad-hoc On-demand Distance Vector)는 필요 시 RREQ(Route Request)를 브로드캐스트하고, 목적지 또는 최신 경로 보유 노드가 RREP(Route Reply)를 되돌려 경로를 확정함.
- **비유**: 모르는 건물에서 목적지를 찾을 때 모든 층 지도를 외우지 않고, 갈림길마다 사람에게 물어 목적지 방향을 이어 가는 방식과 같음.
- **구체 예시**: 노드 A가 D로 전송 시 A -> B -> C -> D 경로를 RREQ/RREP로 구성하고, C-D 링크가 끊기면 RERR(Route Error)로 A에 알린 뒤 재탐색함.
- **흔한 오해·주의점**: Ad-hoc은 Wi-Fi Direct와 동일 개념이 아님. 핵심은 단일 링크 연결이 아니라 다중 홉 라우팅과 토폴로지 변화 대응임.

## 연결 개념
- DSR — 소스 라우팅 기반 On-demand Ad-hoc 라우팅
- OLSR — 주기적 링크 상태 교환 기반 Proactive MANET 라우팅
- Mesh Network — 고정 또는 이동 노드가 다중 홉으로 연결되는 상위 개념

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 단순 무선망 설명이 아니라, 인프라 부재 환경에서 경로 탐색 오버헤드·링크 단절·루프 방지를 어떻게 통제하는지 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Ad-hoc AODV는 이동 노드가 인프라 없이 다중 홉 경로를 필요 시 탐색하는 반응형 라우팅 방식이다.
> 2. **가치**: RREQ/RREP/RERR 제어 메시지로 재난·전장·임시 IoT망에서 AP·기지국 없이 통신 경로를 구성한다.
> 3. **판단 포인트**: 노드 이동성, 경로 단절 빈도, 브로드캐스트 오버헤드, Sequence Number 기반 루프 방지를 함께 판단해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인프라리스 무선망 구조 이해 확인 | 단말 라우터, 다중 홉, 동적 토폴로지 | AP 없는 Wi-Fi 정도로 축소 설명 금지 |
| AODV 경로 탐색 원리 확인 | RREQ, RREP, RERR, Destination Sequence Number | 경로 요청과 경로 응답 방향 혼동 금지 |
| 적용 한계 판단 확인 | 이동성 증가 시 경로 재탐색, 브로드캐스트 폭주 | 재난망 만능 대안으로 단정 금지 |

> 요약: 이 문제는 무선 연결보다 다중 홉 경로 탐색과 링크 단절 대응을 라우팅 관점으로 설명해야 한다.

## Ⅰ. 개요 및 필요성

Ad-hoc AODV는 인프라 없이 이동 노드가 다중 홉 경로를 필요 시 구성하는 라우팅 방식이다. 고정 AP·기지국이 없는 재난·군사·임시 행사망에서는 각 단말이 송수신자이자 라우터가 된다. AODV는 경로를 상시 유지하지 않고 필요 시 탐색해 라우팅 테이블 부담과 제어 트래픽을 줄이는 구조임.

---

## Ⅱ. 구조 및 구성요소

```text
Source Node -> Neighbor Nodes -> Intermediate Relay -> Destination Node
              +-> RREQ Flooding
Destination/Route Holder -> RREP Unicast -> Source Route Table
Broken Link -> RERR -> Upstream Nodes -> Route Rediscovery
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 이동 노드 | 단말·라우터 기능 동시 수행 | 배터리, 무선 링크 품질, 이동성 영향 |
| RREQ | 목적지 경로 요청 브로드캐스트 | Hop Count, Broadcast ID, Sequence Number 포함 |
| RREP | 경로 응답 유니캐스트 | 목적지 또는 최신 경로 보유 노드가 생성 |
| RERR | 링크 단절 알림 | 상위 노드에 경로 무효화 전파 |
| 라우팅 테이블 | 다음 홉·Hop Count·Sequence Number 저장 | 경로 유효시간 기반 삭제 |

> 요약: AODV 구조는 이동 노드, RREQ/RREP/RERR 제어 메시지, 라우팅 테이블이 결합해 필요 시 경로를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
전송 요구 -> 라우팅 테이블 조회 -> 경로 없음
-> RREQ 브로드캐스트 -> 목적지/중간노드 RREP
-> Source 라우팅 테이블 갱신 -> 데이터 전송
-> 링크 단절 감지 -> RERR 전파 -> 재탐색
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 송신 노드가 목적지 경로 존재 여부 확인 | Route Entry, Expiry Time |
| 2 | 경로 없으면 RREQ Flooding 수행 | Broadcast ID 중복 제거 |
| 3 | 목적지 또는 최신 경로 노드가 RREP 반환 | Destination Sequence Number 비교 |
| 4 | 데이터 패킷을 다음 홉으로 전달 | Hop Count, Packet Delivery Ratio |
| 5 | 링크 오류 시 RERR 전파 후 재탐색 | Route Repair Time |

> 요약: AODV는 경로 필요 시 탐색, 사용 중 링크 오류 시 RERR과 재탐색으로 라우팅 상태를 갱신한다.

## Ⅳ. 특징

| 구분 | 기존/대안 | AODV | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 라우팅 방식 | OLSR: 주기적 테이블 유지 | On-demand 경로 탐색 | RFC 3561, RREQ/RREP/RERR |
| 제어 트래픽 | Proactive는 주기 광고 | 경로 필요 시 Flooding | 노드 수 증가 시 RREQ 급증 |
| 루프 방지 | 단순 Hop Count는 루프 위험 | Destination Sequence Number 사용 | 최신 경로 판별 기준 |
| 이동성 대응 | 고정망 라우팅은 수렴 지연 | 링크 단절 감지 후 재탐색 | Route Repair Time 측정 |

> 요약: AODV는 제어 트래픽을 필요 시점으로 제한하지만, 이동성이 클수록 RREQ와 RERR 빈도가 증가한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | AODV | 선택 기준 |
|:---|:---|:---|:---|
| 토폴로지 | 인프라 Wi-Fi | 인프라리스 다중 홉 | AP 설치 불가, 노드 자율 중계 필요 |
| 라우팅 | OLSR Proactive | Reactive On-demand | 통신 세션 간헐적, 노드 수 수십~수백 |
| 운영 | 고정 라우터 관리 | 단말 이동성 기반 경로 변화 | 링크 단절률, 배터리, 무선 간섭 |

> 요약: AODV는 상시 경로 유지 비용보다 필요 시 탐색 비용이 낮은 임시·이동 환경에 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| RREQ 폭주 | 전체 노드 브로드캐스트 | Expanding Ring Search, TTL 제한 | Control Overhead Ratio |
| 경로 단절 | 노드 이동, 무선 음영 | Local Repair, RERR 전파 | Route Breaks per minute |
| 루프·오래된 경로 | 중간 노드 정보 지연 | Destination Sequence Number 비교 | Loop Count 0, stale route ratio |

> 요약: 주요 리스크는 브로드캐스트 오버헤드와 경로 단절이며 TTL·Sequence Number·Local Repair로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 전달률 | Packet Delivery Ratio 95% 이상 | ns-3, OMNeT++, 현장 패킷 로그 |
| 제어 오버헤드 | Control/Data Packet Ratio 20% 이하 | RREQ/RREP/RERR 카운터 |
| 경로 복구 | 평균 Route Repair 1초 이하 | 링크 차단 테스트, 이동 시나리오 |

> 요약: AODV 적용 평가는 전달률, 제어 오버헤드, 경로 복구시간을 동일 시나리오에서 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 재난 현장망은 노드 밀도 50대 기준 TTL 2/4/8 Expanding Ring Search로 RREQ 범위 단계 제어
2. 이동 로봇망은 RSSI 임계값 -80dBm 이하 링크를 사전 감지하고 Local Repair를 500ms 내 수행
3. 보안 통제는 RREQ 위조 방지를 위해 노드 인증, 메시지 무결성 코드, 라우팅 로그 수집 적용

**결론 (2줄):**
- 기술사 판단: 임시·이동·인프라 부재 조건이면 AODV를 선택하고, 고정 대규모망이면 OLSR·OSPF 계열을 우선 검토함
- 향후 방향: MANET은 드론·로봇·재난 IoT와 결합되며 라우팅 보안과 에너지 인지 경로 선택이 병행되어야 함
