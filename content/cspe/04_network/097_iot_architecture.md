## 미리 알고가기

- 센서는 온도와 진동처럼 현장 데이터를 읽는 장치이고 액추에이터는 모터나 밸브처럼 명령을 실행하는 장치임
- 게이트웨이는 현장 장치와 상위 플랫폼 사이에서 프로토콜 변환과 집계를 맡는 중간 장비임
- 엣지는 데이터를 현장 가까이에서 먼저 처리하는 위치를 뜻함
- 디바이스 수명주기는 등록, 인증, 설정, 업데이트, 폐기를 포함한 장치 운영 전 과정을 말함

## Ⅰ. 개요

- **정의/개념**: IoT 아키텍처는 센서와 제어 장치가 만든 데이터를 게이트웨이와 네트워크와 플랫폼을 거쳐 수집하고 분석하고 다시 현장 제어로 돌려보내는 계층 구조임
- **배경/필요성**: 현장 장치는 성능과 전력이 제한되고 통신 방식도 제각각이어서 장치를 직접 클라우드에만 연결하면 보안과 운영과 확장 관리가 모두 어려워짐

## Ⅱ. 특징

- 장치, 게이트웨이, 플랫폼, 응용을 나눠 각 계층 역할을 분리함
- 엣지에서 먼저 필터링과 버퍼링을 하면 불안정한 회선 환경에 더 잘 대응함
- 데이터 수집만으로 끝나지 않고 원격 제어와 장치 관리까지 함께 다룸
- 보안과 인증과 업데이트 구조가 약하면 확장할수록 운영 부담이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 장치 직접 연결형 | 게이트웨이 중심형 |
|:---|:---|:---|
| 구조 | 각 장치가 바로 상위 플랫폼과 통신함 | 현장 게이트웨이가 장치를 묶어 상위와 통신함 |
| 장점 | 구조가 단순하고 초기 구축이 빠름 | 프로토콜 변환과 버퍼링과 보안 통제를 한곳에 모을 수 있음 |
| 단점 | 장치 수가 늘면 관리가 급격히 복잡해짐 | 게이트웨이 설계와 이중화가 필요함 |
| 적합한 환경 | 소규모 단순 센서망 | 산업 현장, 복합 설비, 이기종 장치 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 디바이스 계층 | 센서와 액추에이터가 데이터를 만들고 명령을 수행함 |
| 게이트웨이 계층 | 프로토콜 변환과 집계와 임시 저장과 로컬 제어를 맡음 |
| 네트워크 계층 | 현장과 플랫폼 사이의 메시지 전달 경로를 제공함 |
| 플랫폼 계층 | 수집, 저장, 분석, 규칙 처리, 장치 관리 기능을 제공함 |
| 응용 계층 | 대시보드와 알림과 자동 제어와 업무 연계를 담당함 |

```text
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
| 센서·장치    | -> | 게이트웨이   | -> | 메시지 전송   | -> | 플랫폼 처리   | -> | 응용·제어     |
+-----------+    +-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 데이터 수집    | -> | 현장 전처리    | -> | 상위 전송      | -> | 분석·판단      | -> | 제어·업데이트  |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **데이터 수집**: 센서와 장비가 상태 값을 읽어 냄
2. **현장 전처리**: 게이트웨이가 불필요한 데이터를 줄이고 임시 저장함
3. **상위 전송**: 적절한 메시지 프로토콜로 플랫폼에 전달함
4. **분석과 판단**: 규칙 엔진이나 분석 모듈이 이상 징후를 찾음
5. **제어와 업데이트**: 알림을 보내거나 현장 장치에 다시 명령과 설정을 보냄

## Ⅵ. 실무 적용 및 유의점

1. 공장이나 물류 현장은 회선이 끊겨도 데이터가 유실되면 안 되므로 게이트웨이에 버퍼링과 재전송을 넣고 수집 성공률과 누락률과 재전송 지연을 함께 확인해야 함
2. 장치 수가 많아질수록 인증서와 펌웨어 관리가 병목이 되므로 등록과 갱신 절차를 자동화하고 업데이트 성공률과 비인가 장치 접속 시도를 계속 점검해야 함

## Ⅶ. 결론

IoT 아키텍처의 핵심은 장치를 많이 붙이는 데 있지 않고 현장 제약을 흡수할 게이트웨이와 운영 가능한 장치 관리 구조를 함께 갖추는 데 있음
