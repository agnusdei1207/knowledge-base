# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 통신 중 데이터가 깨지거나 분실되었을 때, 송신자에게 다시 보내달라고 요청하여 오류를 복구하는 기법(ARQ)
- **왜 필요한가**: 유선 케이블이나 무선 전파는 물리적 한계로 항상 노이즈가 발생해 데이터가 깨진다. 무결성을 보장하려면 누군가는 오류를 감지하고 채워넣어야 한다.
- **핵심 직관**: 상대방이 "잘 받았다(ACK)"고 할 때까지 내가 보낸 편지의 사본을 들고 있다가, 시간 내에 답이 없으면 다시 보내는 메커니즘이다.

## 깊이 이해
- **배경·문제의식**: 한 번에 하나씩 보내고 확인받는 정지-대기(Stop-and-Wait) 방식은 신뢰성은 높지만 낭비가 심하다. 회선을 꽉 채워서 보내려면(파이프라이닝) 한 번에 여러 개를 쏘고 나중에 확인받아야 한다.
- **작동 원리**: 크게 세 가지다. 
  1) Stop-and-Wait: 하나 쏘고 멈춰서 기다린다.
  2) Go-Back-N(GBN): 여러 개를 쏘는데, 3번 패킷이 실패하면 3번부터 그 뒤에 보낸 4, 5번까지 전부 다시 쏜다(수신자는 3번이 없으면 4, 5번을 버린다).
  3) Selective Repeat(SR): 3번이 실패하면 딱 3번만 다시 쏜다(수신자가 4, 5번을 버퍼에 저장해둔다).
- **비유**: 피자 1~5조각을 던져준다. 3번 조각이 땅에 떨어졌다. 
  - GBN: "3번부터 5번까지 다 다시 구워와!" (수신자가 4,5번 조각을 버림)
  - SR: "4, 5번은 내가 냉장고에 넣어둘테니, 3번만 새로 구워와!" (수신자가 버퍼 활용)
- **구체 예시**: 위성 통신처럼 핑(RTT)이 500ms에 달하는 환경에서 하나씩 보내면 속도가 안 나온다. 윈도우 크기를 100으로 잡고 GBN이나 SR을 써야 대역폭을 다 쓸 수 있다.
- **흔한 오해·주의점**: GBN은 재전송이 많아서 무조건 SR보다 나쁘다고 생각하기 쉽다. 하지만 SR은 수신자가 패킷 순서를 다시 맞춰야 해서 CPU와 메모리(수신 버퍼) 오버헤드가 크다. 상황에 맞게 쓴다.

## 연결 개념
- 슬라이딩 윈도우 (Sliding Window) — 한 번에 보낼 수 있는 데이터의 양(윈도우)을 이동시키는 기법
- ACK (Acknowledgement) / NAK (Negative ACK) — 수신 확인 / 수신 실패 응답
- Checksum / CRC — ARQ를 작동시키기 위해 데이터가 깨졌는지 판단하는 오류 검출 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ARQ(Automatic Repeat reQuest)는 수신 측의 오류 감지(ACK/NAK)와 송신 측의 타이머 초과(Timeout)를 결합하여 신뢰성을 확보하는 OSI 2/4계층 제어 기법이다.
> 2. **가치**: Stop-and-Wait의 낮은 링크 활용도를 파이프라이닝(Pipelining) 개념으로 개선하여 통신 효율을 극대화한다.
> 3. **판단 포인트**: 통신망의 오류 발생 확률(BER)과 단말의 버퍼 메모리 여력에 따라 대역폭 낭비(GBN)와 수신 버퍼 복잡도(SR) 간의 트레이드오프를 고려하여 방식을 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ARQ의 발전 과정 및 한계 이해 | Stop-and-Wait → Go-Back-N → Selective Repeat 진화 축 | 파이프라이닝 개념 누락, 윈도우 크기 수식 미언급 |
| GBN과 SR의 동작 차이 비교 | 재전송 범위(N개 vs 1개), 누적 ACK vs 개별 ACK | 수신 윈도우 크기 차이(GBN은 1, SR은 송신 윈도우와 동일) 누락 |
| 실무 환경에 따른 기법 선택 역량 | 오류율 높은 무선망(SR)과 광대역 유선망(GBN)의 적용 차이 | 단순히 SR이 GBN보다 "좋다"고 단정짓는 서술 |

> 요약: ARQ는 신뢰성 확보라는 본질 위에서, 대역폭 효율성(링크 활용도)과 메모리 복잡도를 어떻게 맞교환할 것인지 결정하는 메커니즘이다.

## Ⅰ. 개요 및 필요성

- 정의: 송신측이 데이터를 전송한 후 수신측의 응답(ACK/NAK)이나 타이머 만료를 통해 오류를 감지하고 재전송하는 신뢰성 제어 기법
- 배경: 물리 매체(케이블, 전파)의 간섭과 라우터 큐 오버플로우로 인해 데이터 훼손 및 유실(Packet Loss) 필연적 발생
- 필요성: 종단 간(End-to-End) 데이터 무결성을 100% 보장하기 위해 오류 검출과 복구(Retransmission) 메커니즘 필수

---

## Ⅱ. 구조 및 구성요소

```text
[ARQ 핵심 구성요소 및 작동 구조]
송신 윈도우(보낼 수 있는 버퍼) -> 전송 -> 네트워크 매체 -> 수신 윈도우(순서 조립 버퍼)
     | (Timeout 타이머)                                | (CRC 오류 검출)
     +<----------------- ACK / NAK --------------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 송신/수신 윈도우 | 응답 없이 연속으로 전송/수신 가능한 프레임 최대 개수 | 슬라이딩 윈도우 프로토콜의 핵심 변수 |
| Timeout Timer | 패킷 전송 후 응답을 기다리는 제한 시간 | 만료 시 패킷 유실로 간주하고 재전송 |
| ACK / NAK | 정상 수신 확인(ACK) 및 손상 패킷 명시적 재요청(NAK) | GBN은 누적 ACK, SR은 개별 ACK 사용 |
| Sequence 번호 | 전송되는 데이터 프레임의 고유 순서 번호 | 중복 수신 방지 및 재조립 기준 |

> 요약: 송신자는 타이머와 순서 번호를, 수신자는 검출 코드와 응답 메시지를 활용해 양방향 피드백 루프를 구성한다.

## Ⅲ. 동작원리 및 흐름도

```text
[오류 발생 시 재전송 흐름 차이 (예: 프레임 2번 유실, 0~4번 전송 중)]
Go-Back-N (수신 윈도우=1)          Selective Repeat (수신 윈도우>1)
-> 0, 1 정상 수신 (ACK 1)          -> 0, 1 정상 수신 (ACK 1)
-> 2번 유실                        -> 2번 유실
-> 3, 4번 버림 (순서 틀림)         -> 3, 4번 수신 버퍼에 저장 (ACK 3, ACK 4)
-> Timeout(2)                      -> Timeout(2)
-> 2, 3, 4번 일괄 재전송           -> 2번만 단독 재전송
```

| 단계 | 처리 내용 | GBN 방식 | SR 방식 |
|:---:|:---|:---|:---|
| 1 | 프레임 연속 전송 | 송신 윈도우 크기 내 파이프라이닝 | 송신 윈도우 크기 내 파이프라이닝 |
| 2 | 중간 프레임 유실 감지 | 2번 유실 시 이후 3, 4번 자동 폐기 | 3, 4번은 수신 버퍼에 임시 저장 |
| 3 | 수신 응답(ACK) | 정상 수신된 최대 번호 누적 ACK 송신 | 수신된 개별 프레임에 대해 ACK 송신 |
| 4 | 재전송 범위 | 유실된 2번부터 윈도우 내 N개 전체 재전송 | 유실된 2번 1개만 선별적 재전송 |

> 요약: GBN은 수신 버퍼를 아끼기 위해 폐기하고 다 다시 받으며, SR은 대역폭을 아끼기 위해 버퍼에 저장하고 빠진 것만 받는다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| Stop-and-Wait | 1개 전송 후 ACK 대기 (송수신 윈도우=1) | 구현 최하, 링크 활용도(효율) 최저 |
| Go-Back-N | 오류 발생 지점부터 연속 재전송 (수신 윈도우=1) | 수신측 복잡도 최소화, 오류 빈발 시 효율 급감 |
| Selective Repeat | 오류 발생 프레임만 단독 재전송 (수신 윈도우>1) | 재전송 대역폭 최소화, 수신 버퍼 및 재조립 CPU 부하 최고 |

> 요약: 통신 품질이 좋아 오류가 적은 환경에서는 GBN이 유리하고, 대역폭이 좁거나 오류가 잦은 환경에서는 SR이 절대적으로 유리하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Go-Back-N (GBN) | Selective Repeat (SR) | 선택 기준 |
|:---|:---|:---|:---|
| ACK 방식 | 누적 ACK (Cumulative) | 개별 ACK (Independent) | 응답 패킷 유실 시의 강건성 (누적 ACK가 유리) |
| 수신 윈도우 크기 | 1 | N (송신 윈도우 크기와 동일) | 수신 단말의 메모리(버퍼) 가용량 |
| 윈도우 최대 크기 제한 | 2^m - 1$ ($m$은 순서번호 비트수) | 2^{m-1}$ | 순서 번호 혼란을 방지하기 위한 이론적 한계 |
| 재전송 오버헤드 | 크다 (이후 정상 프레임까지 재전송) | 작다 (오류 프레임만 재전송) | 링크의 비트 에러율 (BER) |

> 요약: GBN은 ACK 하나가 유실되어도 다음 누적 ACK로 보완되지만, 무선망처럼 패킷 드롭이 잦은 곳에서는 SR 방식이 트래픽 낭비를 막는 유일한 대안이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Sequence Number 혼동 | 윈도우 크기가 2^m$ 제한을 초과 | SR의 경우 최대 윈도우 크기를 2^{m-1}$로 엄격히 제한 | 시퀀스 번호 중복(Overlap) 발생률 |
| 수신 버퍼 오버플로우 | SR 환경에서 재조립 지연 발생 | 윈도우 크기 동적 조절 및 흐름 제어(Flow Control) 연계 | 수신 버퍼 사용률 < 80% |

> 요약: 프로토콜 설계 시 순서 번호 비트 수에 따른 윈도우 크기 제약을 지키지 않으면 재전송된 패킷을 새 패킷으로 오인하는 치명적 데이터 오염이 발생한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 광케이블 기반 유선망(GBN 채택): BER(Bit Error Rate)이 10^{-9}$ 이하로 극히 낮으므로, 수신 단말의 복잡도를 줄이는 Go-Back-N 방식을 적용해 처리 속도 극대화
2. 위성 및 무선 통신망(SR 채택): 패킷 유실이 잦고 RTT가 큰 위성/해상 무선 통신에서는 대역폭 낭비가 치명적이므로 Selective Repeat 기반의 커스텀 ARQ 설계
3. 현대 TCP의 복합 적용(SACK): TCP는 기본적으로 GBN과 유사한 누적 ACK를 쓰지만, 확장 옵션인 SACK(Selective ACK)를 활성화하여 SR의 장점을 융합 적용

**결론 (2줄):**
- 기술사 판단: 네트워크 신뢰성 통제는 단일 기법이 정답이 아니며, 매체의 오류율(BER)과 단말 성능(버퍼)을 대조하여 GBN과 SR을 취사선택해야 한다.
- 향후 방향: 최근 TCP 병목 극복을 위해 도입된 QUIC이나 현대 TCP 스택은 GBN의 단순함과 SR의 정밀함(SACK)을 혼합하여 동적으로 대응하는 하이브리드 ARQ로 발전하였다.
