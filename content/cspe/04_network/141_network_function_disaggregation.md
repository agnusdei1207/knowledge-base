# 📖 【암기용】 개념 완전 이해

> 목적: CU·DU·RU 기능 분리를 처음 보는 사람도 무선 접속망 구조 변화를 이해하게 만든다.

## 한눈에
- **개요**: 기지국 기능을 중앙 제어, 분산 처리, 무선 장치로 나누는 RAN 구조
- **왜 필요한가**: 5G 기지국은 트래픽·지연·셀 밀도 요구가 커져 단일 장비 방식으로는 배치 유연성과 벤더 선택권을 확보하기 어렵다.
- **핵심 직관**: 기지국을 한 덩어리 장비가 아니라 본사 서버, 지역 처리장, 안테나 현장 장치로 나누어 운영하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 전통 기지국은 BBU와 RU가 벤더 종속 장비로 묶였고, 무선 기능 확장 때 장비 전체 교체 비용이 발생했다.
- **작동 원리**: CU는 RRC·PDCP 등 상위 계층을 담당하고, DU는 RLC·MAC·High-PHY를 처리하며, RU는 Low-PHY·RF 송수신을 담당한다.
- **비유**: 방송국에서 편성팀이 CU, 송출실이 DU, 송신탑이 RU 역할을 맡아 하나의 방송 서비스를 만든다.
- **구체 예시**: O-RAN Split 7.2x는 DU와 RU 사이에 eCPRI 기반 프런트홀을 사용하고, 프런트홀 지연·동기 요구를 별도 관리한다.
- **흔한 오해·주의점**: 기능을 나누면 모든 지연 문제가 사라지는 것이 아니라, CU-DU-RU 사이 전송망 지연·동기·운영 복잡도가 새 제약이 된다.

## 연결 개념
- vRAN - DU·CU 기능을 COTS 서버와 가상화 계층에서 실행
- O-RAN - 개방형 인터페이스와 RIC 기반 제어 구조 제공
- eCPRI - DU와 RU 사이 프런트홀 전송에 사용되는 패킷 기반 인터페이스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 기능 분리 명칭이 아니라 인터페이스, 지연, 운영 책임을 구분한다.
> 핵심: 출제자는 CU·DU·RU 역할과 O-RAN 구조를 통해 RAN 개방화의 장점·제약·검증 지표를 묻는다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 네트워크 기능 분리는 기지국을 CU, DU, RU로 나누어 제어·분산 처리·무선 송수신 기능을 분리하는 RAN 구조이다.
> 2. **가치**: O-RAN 기반 개방 인터페이스로 벤더 종속을 줄이고, CU 중앙집중과 DU 현장 배치를 업무별로 조합한다.
> 3. **판단 포인트**: RU-DU 프런트홀 지연, 시간 동기, 벤더 간 상호운용성, 장애 책임 경계를 함께 판단해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 5G RAN 구조 이해 확인 | CU·DU·RU 기능, F1, eCPRI, O-RAN Split 7.2x | CU와 DU 역할을 단순 서버 위치 차이로만 설명 |
| 개방형 RAN 도입 판단 확인 | 벤더 분리, 프런트홀 지연, PTP 동기, 상호운용 시험 | 개방 인터페이스를 비용 절감으로만 단정 |
| 운영 리스크 인식 확인 | 장애 구간 분리, SLA, 성능 카운터, 책임 경계 | RU 장애와 DU 처리 병목을 같은 원인으로 취급 |

> 요약: 이 문제는 CU·DU·RU 역할 암기가 아니라 인터페이스별 지연·동기·운영 책임을 구분하는 판단을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 기지국 기능을 CU·DU·RU로 분리
- 배경: 전통 BBU-RRU 일체형 구조는 벤더 장비 교체 단위가 크고 상호운용 시험 범위가 제한됨.
- 필요성: 5G 셀 밀도 증가, MEC 연계, O-RAN 개방 인터페이스 요구로 기능별 배치와 운영 분리가 필요함.
- 판단 기준: 프런트홀 지연, PTP 시간 동기, F1 인터페이스, O-RAN 상호운용 시험 결과로 도입 여부를 판단함.

---

## Ⅱ. 구조 및 구성요소

```text
5G Core -> CU -> F1 -> DU -> eCPRI / Open Fronthaul -> RU -> Antenna
           |          |                                |
           +-> RRC    +-> MAC / High-PHY               +-> RF / Low-PHY
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CU | RRC, SDAP, PDCP 등 상위 계층 처리 | 중앙 사이트 배치로 제어 집중 |
| DU | RLC, MAC, High-PHY 처리 | 셀 인접 위치 배치로 지연 통제 |
| RU | Low-PHY, RF 송수신, 안테나 연결 | eCPRI, Open Fronthaul, PTP 동기 필요 |
| RAN Transport | Midhaul, Fronthaul 전송 | 지연, 지터, 패킷 손실을 계층별로 측정 |

> 요약: CU는 제어와 상위 계층, DU는 실시간 무선 처리, RU는 RF 송수신을 담당하며 F1과 eCPRI가 경계를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
단말 접속 -> RU RF 수신 -> DU MAC / PHY 처리 -> CU RRC / PDCP 처리
-> 5G Core 연동 -> 정책 적용 -> 사용자 데이터 전달
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | RU가 무선 신호를 RF와 Low-PHY 단위로 처리 | RSSI, SINR, RU alarm |
| 2 | DU가 스케줄링, HARQ, MAC 처리를 수행 | PRB 사용률, HARQ retransmission |
| 3 | CU가 RRC 연결, PDCP, 이동성 제어를 수행 | RRC setup success rate |
| 4 | Core가 세션과 정책을 적용 | PDU session success rate |
| 5 | OAM이 장애 구간과 지표를 수집 | F1/eCPRI 지연, PTP offset |

> 요약: 단말 트래픽은 RU, DU, CU, Core 순서로 처리되며 실시간성은 DU-RU 경계에서 가장 엄격하게 관리된다.

---

## Ⅳ. 특징

| 구분 | 기존 일체형 RAN | CU·DU·RU 기능 분리 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 구조 | BBU-RRU 벤더 묶음 | CU-DU-RU 계층 분리 | F1, eCPRI, O-RAN Open Fronthaul |
| 배치 | 기지국 장비 중심 | CU 중앙, DU 엣지, RU 현장 | 지연 요구에 따라 CU/DU 위치 결정 |
| 운영 | 장애 원인 장비 단위 추적 | 인터페이스별 성능 카운터 추적 | PRB, BLER, F1 latency, PTP offset |
| 한계 | 벤더 변경 범위 제한 | 상호운용 시험과 동기 설계 필요 | O-RAN PlugFest, IEEE 1588 PTP |

> 요약: 기능 분리는 RAN 개방성과 배치 선택권을 제공하지만 프런트홀 지연·시간 동기·상호운용 검증을 운영 과제로 만든다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 통합 BBU | CU·DU·RU 분리 | 벤더 혼합과 MEC 연계 요구 존재 시 선택 |
| 비용/성능 | 장비 단위 증설 | 기능 단위 증설 | DU CPU 사용률, RU 포트 수, 프런트홀 대역폭으로 산정 |
| 운영/위험 | 단일 벤더 책임 | 다중 벤더 책임 | 장애 책임 경계와 IOT 결과 확보 시 적용 |

> 요약: 기능 분리는 개방형 조달보다 인터페이스 검증과 운영 책임 분리가 준비된 사업자에게 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 프런트홀 지연 | DU-RU 거리와 패킷 지터 증가 | TSN, QoS, PTP 경로 설계 | one-way delay, jitter |
| 동기 오류 | RU와 DU 시간 기준 불일치 | IEEE 1588 PTP, SyncE 적용 | PTP offset, holdover alarm |
| 상호운용 장애 | 벤더별 O-RAN 옵션 차이 | 사전 IOT, PlugFest 결과 확인 | call setup success, KPI regression |

> 요약: 주요 위험은 지연, 동기, 상호운용이며 각 위험은 전송망·시간원·시험 절차로 분리 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 프런트홀 품질 | 지연·지터 설계 기준 준수 | eCPRI 패킷 측정, TWAMP |
| 무선 품질 | BLER, RRC success, handover success 기준 충족 | RAN PM counter |
| 운영 통제 | CU/DU/RU 장애 구간 식별 | OAM alarm, log correlation |

> 요약: 도입 후에는 전송 품질, 무선 품질, 장애 구간 식별률을 함께 측정해야 기능 분리 효과를 판정할 수 있다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. RU-DU 구간은 eCPRI, QoS, IEEE 1588 PTP 기준으로 프런트홀 지연·동기 설계를 먼저 확정함.
2. CU-DU 구간은 F1 인터페이스, 장애 알람, PM 카운터 기준으로 운영 책임 경계를 문서화함.
3. 다중 벤더 도입 전 O-RAN 상호운용 시험, 통화 성공률, 핸드오버 성공률 회귀 시험을 수행함.

**결론 (2줄):**
- 기술사 판단: 단일 벤더 소형망이면 통합 RAN, 대규모 5G·MEC·벤더 분리 요구가 있으면 CU·DU·RU 분리를 선택함.
- 향후 방향: O-RAN RIC와 xApp/rApp 기반 제어가 결합되면서 기능 분리는 RAN 자동화의 전제 구조가 됨.
