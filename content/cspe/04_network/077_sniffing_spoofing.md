## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 스니핑은 네트워크 상의 패킷을 몰래 엿보는 도청 행위이며, 스푸핑은 송신자 IP나 MAC 등 식별 정보를 위조하여 신분을 속이는 기만 공격 |
| **배경/필요성** | 평문 통신 환경과 인증이 부족한 2/3계층 프로토콜 취약점을 노린 데이터 탈취 및 권한 탈취 방어 필요 |
| **출제 의도** | Promiscuous 모드, ARP/IP 스푸핑 원리 및 이를 방어하기 위한 암호화와 포트 보안 기술 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
| Attacker |       | Switch   |       | Victim   |
| (Spoof)  | <---> | (Mirror) | <---> | (Client) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Sniffing (도청) | 흐르는 패킷을 무단 수집(WireShark 등)하여 평문 ID/PW 및 데이터 유출 유발 | 통화 엿듣기 |
| Spoofing (위조) | ARP, IP, DNS 등 정보를 변조하여 해커를 정상 시스템(게이트웨이 등)으로 오인시킴 | 신분증 위조 |
| Promiscuous | 자신의 MAC 주소가 아닌 패킷까지 모두 수신 처리하도록 설정된 랜카드 모드 | 모든 우편물 강제 수신 |

> 요약: 스푸핑으로 트래픽을 자신에게 유도한 후(MITM), 스니핑으로 기밀 데이터를 훔치는 연계 공격이 일반적임

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 목표 선정| -> | ARP 위조 | -> | 패킷 도청| -> | 정보 유출|
+----------+    +----------+    +----------+    +----------+
```
1. 목표 선정: 동일 서브넷 내부의 취약한 단말과 게이트웨이(라우터) 사이의 통신을 타겟 지정
2. ARP 위조: 해커가 가짜 ARP 응답을 보내 단말의 ARP 테이블 상 게이트웨이 MAC을 해커 MAC으로 변조 (스푸핑)
3. 패킷 도청: 단말이 외부로 보내는 모든 트래픽이 해커 PC를 경유하게 만들어 패킷 수집 (스니핑)
4. 정보 유출: 수집된 패킷 내의 평문 HTTP, Telnet, FTP 세션 등에서 아이디와 패스워드 추출

> 요약: 식별자 위조(스푸핑)로 트래픽 흐름을 왜곡한 뒤 평문 데이터를 몰래 탈취(스니핑)함

## Ⅳ. 문제점
- L2 스위치 환경에서 ARP 프로토콜은 인증 기능이 없어 위조된 응답을 그대로 수용 (ARP 캐시 오염 원인)
- Telnet, FTP, HTTP 등 레거시 프로토콜은 데이터를 암호화 없이 평문으로 전송하여 스니핑 시 100% 노출
- 외부 인터넷 망에서 Source IP를 위조(IP 스푸핑)하여 DDoS 공격 수행 시 방어 장비의 추적 및 차단 곤란

## Ⅴ. 개선방안
- [단기] 모든 관리 및 서비스 프로토콜을 암호화 통신(SSH, SFTP, HTTPS)으로 즉시 전환하여 도청 무력화
- [중기] L2 스위치에 Dynamic ARP Inspection(DAI) 설정 및 정적(Static) ARP 바인딩으로 위조 원천 방어
- [장기] 네트워크 엣지에 uRPF(Unicast Reverse Path Forwarding) 적용하여 위조된 소스 IP 패킷 자동 차단

## Ⅵ. 전망
- 네트워크의 기본 원칙이 '신뢰 방어'에서 어떠한 접근도 의심하는 제로 트러스트(Zero Trust) 아키텍처로 진화할 것임
