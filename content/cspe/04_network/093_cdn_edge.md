## Ⅰ. 개요
- **정의**: 사용자 근처 PoP에 콘텐츠를 캐싱하여 지연을 줄이는 분산 전송 인프라
- **배경/필요성**: 오리진 서버 집중 시 거리 비례 지연과 대역폭 병목이 발생함
- **비유**: 출판사(오리진)가 전국 서점(PoP)에 재고를 미리 배치하는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 콘텐츠 전송 최적화 원리 | 캐시 히트율·PoP 배치 전략 | Edge Computing(091 참조)과 역할 차이 구분 |

> 요약: 지리적으로 분산된 PoP 캐시를 통해 콘텐츠 전송 지연을 줄이는 인프라임

## Ⅱ. 구성요소
```text
[Client] --> [Edge PoP] --cache miss--> [Origin]
                |
           cache hit 응답
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Edge PoP | 사용자 인접 지역에 배치된 캐시 서버 클러스터 | 동네 서점 |
| Origin Server | 원본 콘텐츠를 보유한 소스 서버 | 출판사 창고 |
| GSLB | DNS 기반으로 최적 PoP를 선택하는 글로벌 로드밸런서 | 가장 가까운 서점 안내 |
| Cache Policy | TTL·Purge·Invalidation 등 캐시 갱신 규칙 | 재고 회전 정책 |

> 요약: GSLB가 최적 PoP를 선택하고, 캐시 정책에 따라 콘텐츠를 제공함

## Ⅲ. 절차
```text
DNS 질의 --> PoP 선택 --> 캐시 조회 --> 오리진 폴백
```
- 1단계: 클라이언트 DNS 질의 시 GSLB가 지연·부하 기반으로 최적 PoP 반환함
- 2단계: 클라이언트가 선택된 Edge PoP에 콘텐츠 요청함
- 3단계: 캐시 히트 시 즉시 응답, 미스 시 오리진에 요청 후 캐시 저장함
- 4단계: 캐시 정책(TTL 만료·Purge)에 따라 주기적으로 콘텐츠를 갱신함

> 요약: DNS 기반 PoP 선택 후 캐시 히트/미스에 따라 콘텐츠를 제공함

## Ⅳ. 문제점
- 캐시 일관성: TTL 만료 전 오리진 변경 시 구버전 콘텐츠가 제공됨
- 동적 콘텐츠 한계: API 응답 등 개인화 콘텐츠는 캐시 적용이 어려움
- PoP 비용: 글로벌 PoP 확장에 따른 인프라·운영 비용이 증가함

> 요약: 일관성·동적콘텐츠·비용이 CDN 운영의 핵심 과제임

## Ⅴ. 개선방안
1. 단기: Instant Purge API 도입으로 캐시 무효화 지연을 수 초 이내로 단축
2. 중기: Edge Function(서버리스) 활용으로 동적 콘텐츠 엣지 처리 구현
3. 장기: PoP 자동 스케일링·피어링 최적화로 비용 대비 커버리지 개선

> 요약: 즉시무효화-엣지함수-자동스케일링 순으로 CDN 한계를 극복함

## Ⅵ. 전망
- 발전 방향: CDN이 Edge Computing 플랫폼으로 확장되는 추세(엣지 서버리스)
- 기술사적 판단: 미디어 스트리밍·WebRTC 등 실시간 콘텐츠 수요 증가로 역할 확대
- 기술사 제언: 캐시 전략과 엣지 로직 분리 설계로 유연한 CDN 아키텍처 수립 필요
