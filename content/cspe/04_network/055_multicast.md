## Ⅰ. 개요
- **정의**: 하나의 송신자가 특정 그룹에 가입한 다수 수신자에게 동시에 데이터를 전달하는 통신 방식임
- **배경/필요성**: 동일 데이터를 N명에게 유니캐스트로 전송하면 송신자 대역폭이 N배 소모되므로 네트워크 효율적 그룹 전송이 필요함
- **비유**: 라디오 방송국이 한 번 송출하면 주파수를 맞춘 모든 수신기가 동시에 청취하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Unicast/Broadcast와 비교, IGMP·PIM 동작 | 그룹 관리(IGMP)와 라우팅(PIM) 분리 | Anycast(054)와 혼동 금지 |

> 요약: 그룹 가입 기반으로 단일 스트림을 다수 수신자에게 효율적으로 전달하는 방식임

## Ⅱ. 구성요소
```text
Sender --> Router(PIM) --+--> Router --> Receiver A
                         +--> Router --> Receiver B
                         +--> Router --> Receiver C
              IGMP으로 그룹 가입/탈퇴 관리
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Multicast Group | Class D IP(224.0.0.0/4)로 식별되는 수신자 논리 그룹 | 라디오 주파수 채널 |
| IGMP | 호스트와 로컬 라우터 간 그룹 가입·탈퇴를 관리하는 프로토콜 | 채널 구독 신청서 |
| PIM | 라우터 간 멀티캐스트 트리를 구성하는 라우팅 프로토콜(SM/DM) | 방송 중계탑 간 연결 |
| Distribution Tree | 송신자에서 수신자까지의 패킷 복제 경로(SPT, RPT) | 방송 송출 네트워크 |

> 요약: IGMP로 그룹을 관리하고 PIM으로 Distribution Tree를 구성하여 패킷을 복제·전달함

## Ⅲ. 절차
```text
그룹 가입 --> 트리 구성 --> 데이터 전송 --> 그룹 탈퇴/유지
```
- 1단계: 수신자가 IGMP Join 메시지로 멀티캐스트 그룹에 가입을 요청함
- 2단계: PIM 라우터가 RP(Rendezvous Point) 기반 공유 트리 또는 SPT를 구성함
- 3단계: 송신자 데이터가 트리 경로를 따라 분기점에서 복제되어 각 수신자에게 전달됨
- 4단계: IGMP Leave 또는 타임아웃으로 수신자가 탈퇴하면 해당 브랜치가 가지치기(Prune)됨

> 요약: 그룹 가입 → 트리 구성 → 데이터 복제 전달 → 탈퇴/가지치기의 라이프사이클임

## Ⅳ. 문제점
- 라우터 지원 부족: 인터넷 구간 라우터 중 PIM 미지원 장비가 많아 글로벌 배포가 어려움
- 신뢰성 부재: UDP 기반이므로 패킷 손실 시 재전송 메커니즘이 없음 — 품질 저하
- 그룹 관리 오버헤드: 대규모 그룹에서 IGMP 상태 유지가 라우터 메모리를 과다 소모함

> 요약: 라우터 호환성, 신뢰성 부재, 상태 관리 오버헤드가 주요 과제임

## Ⅴ. 개선방안
1. 단기: 터널링(GRE, VXLAN)으로 비지원 구간을 우회하여 멀티캐스트 도달성을 확보함
2. 중기: NACK 기반 신뢰적 멀티캐스트 프로토콜(PGM 등) 적용으로 손실 복구를 지원함
3. 장기: SDN 컨트롤러 기반 동적 트리 관리로 그룹 상태 오버헤드를 중앙 집중 처리함

> 요약: 터널링, 신뢰적 프로토콜, SDN 기반 관리로 단계별 개선이 가능함

## Ⅵ. 전망
- 발전 방향: IPTV·실시간 스트리밍에서 오버레이 멀티캐스트와 SDN 연계로 활용 확대 중임
- 기술사적 판단: 5G MBS(Multicast Broadcast Service) 표준화로 모바일 멀티캐스트 수요가 증가함
- 기술사 제언: 멀티캐스트 설계 시 유니캐스트 폴백 전략과 QoS 정책(056 참조) 연계가 필요함
