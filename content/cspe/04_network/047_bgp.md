## Ⅰ. 개요
- **정의**: BGP(Border Gateway Protocol)는 독립적인 라우팅 정책을 가진 대규모 네트워크 그룹(AS, Autonomous System) 간 경로를 교환하는 외부 라우팅 프로토콜임.
- **배경/필요성**: 수십만 개 라우터로 구성된 인터넷 망에서 단순 거리/비용 외에 비즈니스, 보안 등 정책 기반의 경로 선택 메커니즘 필요.
- **출제 의도**: BGP의 경로 벡터(Path Vector) 특성, iBGP와 eBGP의 차이점, BGP 속성을 이용한 경로 결정 원리 파악.

## Ⅱ. 구성요소
```text
+-------------------+            +-------------------+
|       AS 100      |    eBGP    |       AS 200      |
|  [R1] <-----> [R2]|<---------->|[R3] <-----> [R4]  |
|      (iBGP)       |            |      (iBGP)       |
+-------------------+            +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| AS (Autonomous Sys)| ISP(통신사), 대기업 등 독립된 단일 라우팅 관리 정책을 가지는 거대 네트워크 단위 | 하나의 국가 |
| eBGP | 서로 다른 AS(국가) 간에 국경 라우터를 통해 경로 정보를 주고받는 프로토콜 연결 | 국가 간 외교망 |
| iBGP | 동일한 AS 내부의 라우터들끼리 외부에서 배워온 BGP 경로 정보를 전파하는 연결 | 국내 연락망 |
> 요약: 세계 인터넷 망은 여러 AS의 집합이며, AS 간 통신(eBGP)과 내부 전파(iBGP)로 글로벌 라우팅이 완성됨.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| TCP 연결  |-> | 경로 교환   |-> | 정책/속성비교|-> | 최적경로선정|
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **TCP 연결**: 피어(Peer) 라우터 간에 TCP 179번 포트를 통해 신뢰성 있는 BGP 세션을 확립함.
2. **경로 교환**: 서로의 라우팅 정보(NLRI)와 경로가 거쳐온 AS 번호 목록(AS-Path)을 교환함.
3. **정책/속성 비교**: 수신한 경로들에 대해 로컬 정책 속성(Weight, Local Preference, AS-Path 길이 등)을 순차적으로 비교 평가함.
4. **최적 경로 선정**: 가장 우선순위가 높은 단일 최적 경로를 라우팅 테이블에 등록하고 인접 피어에 전파함.
> 요약: BGP는 무조건 빠른 길이 아닌, 관리자가 설정한 다양한 속성(조건)에 부합하는 길을 우선하여 선택함.

## Ⅳ. 문제점
- **수렴 속도(Convergence) 저하**: 인터넷 전체의 라우팅 테이블이 방대하여 링크 장애 시 대체 경로 계산 및 전파에 수 분 이상 소요.
- **BGP 하이재킹 취약점**: 누군가 악의적(또는 실수)으로 타인의 IP 대역을 자신이 소유한 것처럼 BGP에 광고하면 트래픽이 탈취됨.
- **iBGP 풀 메시 구조의 오버헤드**: 루핑 방지 원칙에 따라 iBGP 라우터들은 모두 1:1로 직접 연결되어야 하므로 설정 및 세션 부하 증가.

## Ⅴ. 개선방안
- **iBGP 확장성 개선**: Route Reflector(RR)나 AS Confederation을 도입하여 풀 메시 구성으로 인한 세션 오버헤드 완화 (단기).
- **보안 검증 도입**: RPKI(Resource Public Key Infrastructure)를 연동하여 BGP 라우팅 업데이트의 출처(Origin)를 암호학적으로 검증 (중기).
- **차세대 BGP 보안**: 경로 전체의 무결성을 보장하는 BGPsec 프레임워크 표준 전면 채택 (장기).

## Ⅵ. 전망
- 글로벌 인터넷 백본을 지탱하는 유일무이한 EGP로서 당분간 이를 대체할 기술은 나타나지 않을 것임.
- 데이터센터 내부 네트워크에서도 확장성과 안정성을 인정받아 Leaf-Spine 아키텍처의 핵심 라우팅 프로토콜로 광범위하게 사용되고 있음.
