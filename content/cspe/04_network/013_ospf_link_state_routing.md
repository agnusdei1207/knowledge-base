# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: OSPF(Open Shortest Path First)는 각 라우터가 자기 링크 상태(LSA)를 전 영역에 뿌려 모두가 동일한 망 지도(LSDB)를 만들고, 그 지도 위에서 Dijkstra 알고리즘으로 최단경로를 계산하는 대표적 링크 상태(Link State) IGP임(정적·동적 기본은 012 참조).
- **왜 필요한가**: 거리 벡터(RIP, 014 참조)는 이웃이 알려준 홉 수만 믿어 전체 지형을 몰라 수렴이 느리고 루프에 취약한데, OSPF는 모든 라우터가 지도 전체를 공유하므로 수초 내 빠르고 루프 없는 수렴이 가능함.
- **핵심 직관**: 옆 사람 말만 듣고 길을 찾는 게 거리 벡터라면, OSPF는 모두가 같은 전체 지도를 손에 쥐고 각자 최단경로를 직접 계산하는 것과 같음.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래는 답안(Ⅰ~Ⅵ·표)에 나오는 용어를 미리 풀어 둔 것임. 최상위 키워드는 **링크 상태 라우팅(OSPF)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| LSA(Link State Advertisement) | 라우터가 광고하는 자기 링크·비용 정보 조각 | 지도의 한 조각 타일 |
| LSDB(Link State DB) | 모든 LSA를 모아 만든 영역 전체 지도 | 완성된 전체 지도책 |
| SPF/Dijkstra | LSDB 위에서 최단경로 트리를 계산하는 알고리즘 | 지도 보고 최단길 계산 |
| Cost(비용) | 링크 대역폭 기반 메트릭(기본 10^8/대역폭) | 도로의 통행 점수 |
| Area(영역) | LSDB를 나누는 라우팅 단위, 0=백본 | 지도를 구역으로 분할 |
| ABR(Area Border Router) | 영역 경계에 걸친 라우터 | 구역 사이 관문 |
| ASBR | 외부 경로를 OSPF로 주입하는 라우터 | 외부 세계로의 출입국 |
| DR/BDR | 브로드캐스트망 대표·백업 라우터 | 반장·부반장 |
| Hello 패킷 | 이웃 발견·생존 확인 메시지 | 서로 안부 인사 |
| Adjacency(인접) | LSDB를 동기화하는 이웃 관계 | 지도 공유 짝꿍 |
| Router-ID | 라우터를 식별하는 32비트 값 | 라우터 주민번호 |
| OSPFv3 | IPv6를 지원하는 OSPF 버전(RFC 5340) | IPv6판 지도 프로토콜 |

## 깊이 이해
- **배경·문제의식**: 초기 RIP는 홉 수 15 제한·주기적 전체 테이블 방송·느린 수렴(카운트 투 인피니티)으로 대규모 망에 부적합했음. IETF는 벤더 종속 없는(Open) 표준 IGP로 OSPF(RFC 2328, v2)를 만들어 대역폭 기반 비용과 빠른 수렴을 제공함.
- **작동 원리(어떻게+왜)**: ① 라우터가 Hello로 이웃을 찾아 Adjacency를 맺고, ② 각자 자기 링크 상태를 LSA로 만들어 영역 내에 Flooding(홍수처럼 전파)하며, ③ 모든 라우터가 같은 LSDB(지도)를 갖게 되면, ④ 각자 자신을 루트로 Dijkstra(SPF)를 돌려 목적지별 최단경로 트리를 만들어 라우팅 테이블에 넣음. 지도를 공유하고 각자 계산하기에 루프가 원천 차단되고, 변화가 생긴 LSA만 갱신 Flooding하므로 수렴이 빠름.
- **비유**: RIP가 "다음 마을까지 몇 정거장?"을 옆 사람에게 물어 전달받는 방식이라면, OSPF는 모두에게 동일한 지하철 노선도를 나눠주고 각자 출발역에서 최단 경로를 직접 그리는 방식임.
- **구체 예시**: 1Gbps 링크의 기본 Cost는 10^8/10^9 계산상 1 미만이라 최소 1로 처리되므로, 실무에서는 기준 대역폭(reference-bandwidth)을 100Gbps 등으로 올려 10G·40G·100G를 구분함. 캠퍼스망에서 코어 링크 하나가 끊기면 해당 LSA가 재Flooding되고 각 라우터가 SPF를 재계산해 대개 1~5초 내 우회 경로로 수렴함.
- **흔한 오해·주의점**: OSPF Cost는 홉 수가 아니라 대역폭 기반임(RIP와 혼동 금지). 또한 Area는 많을수록 좋은 게 아니라 모든 비백본 Area는 반드시 Area 0(백본)에 접해야 하며, 규모가 커질수록 LSDB·SPF 부하를 줄이기 위해 Area를 나눔.

## 연결 개념
- 라우팅 기본·AD (012 참조) — OSPF의 관리거리(AD)는 110으로, 정적(1)보다 낮은 우선순위임.
- 거리 벡터·RIP (014 참조) — 링크 상태의 대척점. 지도 없이 홉 수만으로 판단.
- BGP (015 참조) — OSPF는 AS 내부(IGP), BGP는 AS 간(EGP) 경로 결정으로 역할이 다름.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OSPF는 LSA로 링크 상태를 Flooding해 모든 라우터가 동일한 LSDB(지도)를 공유하고, 각자 Dijkstra로 최단경로를 계산하는 링크 상태 IGP임.
> 2. **가치**: 대역폭 기반 Cost와 지도 공유로 빠르고 루프 없는 수렴을 제공하며, Area로 대규모 망의 LSDB·SPF 부하를 계층 분할함.
> 3. **판단**: 단일 AS 내부의 중대규모 이중화 망에 적합하며, AS 간 정책 라우팅은 BGP(015 참조)에 위임하고 IPv6는 OSPFv3로 확장함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 링크 상태 동작 원리 | LSA Flooding·LSDB 동기화·Dijkstra(SPF) | Cost를 홉 수로 오설명 |
| 계층 구조 설계 | Area·백본(0)·ABR/ASBR 역할 | 비백본 Area의 백본 접속 요건 누락 |
| 타 프로토콜과의 위치 | IGP(OSPF) vs EGP(BGP), 거리 벡터 대비 | RIP·BGP 세부와 혼동 |

> 요약: OSPF는 'LSDB 공유 + 각자 SPF 계산'으로 루프 프리 수렴을 증명하고, Area 계층 설계와 IGP/EGP 위치로 결론지어야 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 링크 상태를 LSA로 광고·동기화해 만든 LSDB 위에서 Dijkstra로 최단경로를 계산하는 표준 IGP임.
- 배경: RIP의 홉 15 제한·느린 수렴·루프 취약을 극복하기 위한 대역폭 기반·계층형 라우팅이 필요함.
- 필요성: 대규모 이중화 망에서 수초 내 자동 우회와 루프 프리 경로를 보장하고, 벤더 종속 없이(Open) 상호운용해야 함.

---

## Ⅱ. 구조 및 구성요소

구조도(선형):

```text
Area 0 (백본)
  R1 <-> R2 : Hello로 이웃 발견 -> Adjacency 형성 -> LSA 교환 -> LSDB 동기화
  각 라우터: LSDB 지도 -> SPF(Dijkstra) 계산 -> 라우팅 테이블 생성
Area 1 --(ABR)-- Area 0 --(ABR)-- Area 2   (모든 Area는 백본에 접속)
외부망(RIP/BGP) --(ASBR)--> OSPF로 경로 재분배(Redistribution)
```

| 구성요소 | 역할 | 특징 |
|:---|:---|:---|
| LSA/LSDB | 링크 상태 광고·전체 지도 저장 | Type 1~7, 영역별 동기화 |
| SPF(Dijkstra) | LSDB로 최단경로 트리 계산 | 각 라우터가 독립 수행 |
| Area·백본(0) | 라우팅 계층 분할 단위 | 비백본은 반드시 0에 접속 |
| ABR/ASBR | 영역 경계·외부경로 주입 | 요약(Summary)·재분배 담당 |
| DR/BDR | 브로드캐스트망 대표 선출 | 인접 수 O(n^2)→O(n) 절감 |

> 요약: OSPF는 LSA로 LSDB를 동기화하고 각 라우터가 SPF를 돌리며, Area·ABR/ASBR로 대규모 망을 계층화함.

---

## Ⅲ. 동작원리 및 흐름도

흐름도(선형):

```text
라우터가 Hello 송신 -> 이웃 발견 -> 파라미터 일치 시 Adjacency 형성
  -> 각 라우터가 자기 LSA를 영역에 Flooding -> 모든 라우터 LSDB 동일화
  -> 각 라우터가 자신을 루트로 SPF(Dijkstra) 계산 -> 최단경로 테이블 반영
  -> 링크 변화 시 변경 LSA만 재Flooding -> 부분 재계산으로 빠른 수렴
```

- 1단계: 라우터가 인터페이스로 Hello를 보내 이웃을 발견하고, Area·서브넷·타이머가 일치하면 Adjacency를 맺음.
- 2단계: 각 라우터가 자신의 링크·Cost를 담은 LSA를 만들어 영역 내 모든 라우터에 Flooding함.
- 3단계: 모든 라우터가 동일한 LSDB(지도)를 확보하고, 각자 자신을 루트로 Dijkstra를 수행해 목적지별 최단경로를 산출함.
- 4단계: 링크 장애·비용 변경이 생기면 해당 라우터가 갱신 LSA만 재Flooding하고, 각 라우터가 SPF를 재계산해 우회 경로로 수렴함.

> 요약: 라우터는 Hello로 인접을 맺고 LSA를 Flooding해 LSDB를 동기화한 뒤 각자 SPF로 경로를 정하며, 변경분만 재전파해 빠르게 수렴함.

---

## Ⅳ. 특징

- 루프 프리 수렴: 모든 라우터가 동일 LSDB로 각자 SPF를 계산하므로, 거리 벡터의 카운트 투 인피니티(014 참조) 같은 루프가 구조적으로 발생하지 않음.
- 대역폭 기반 Cost: 메트릭이 홉 수가 아니라 대역폭(10^8/BW)이라 고속 회선을 선호하며, reference-bandwidth 조정으로 10G 이상 링크를 구분함.
- 계층적 확장성: Area로 LSDB·SPF 범위를 국소화하고, ABR이 경로를 요약(Summary)해 코어의 LSA 수와 재계산 부하를 줄임.
- 인접 최적화: 브로드캐스트망에서 DR/BDR을 선출해 인접 수를 O(n^2)에서 O(n)으로 낮추고 Flooding 트래픽을 절감함.
- 이중 스택 지원: OSPFv2는 IPv4, OSPFv3(RFC 5340)는 IPv6를 담당하며 링크 로컬 주소·주소군(AF) 확장으로 이중 스택을 처리함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | OSPF(링크 상태) | RIP(거리 벡터, 014 참조) |
|:---|:---|:---|
| 경로 정보 | LSDB 전체 지도 공유 | 이웃이 준 목적지별 거리만 |
| 메트릭 | 대역폭 기반 Cost | 홉 수(최대 15) |
| 알고리즘 | Dijkstra(SPF) | Bellman-Ford |
| 수렴 속도 | 변경분 Flooding으로 빠름 | 주기 갱신·느림, 루프 취약 |
| 확장성 | Area 계층으로 대규모 가능 | 소규모 망 한정 |

> 요약: 지도 공유·SPF의 OSPF는 빠른 루프 프리 수렴과 계층 확장에 강해, 홉 수 기반 RIP를 사실상 대체하는 표준 IGP임.

리스크·대응(불릿):
- SPF 재계산 폭주 — 불안정 링크의 잦은 LSA Flooding(Flapping) — SPF/LSA Throttling·인터페이스 Dampening 적용.
- LSDB 비대화 — 단일 대형 Area·불필요 외부경로 주입 — Area 분할·ABR Summary·Stub/NSSA Area 사용.
- 경로 오주입 — 신뢰 못 할 이웃의 LSA — OSPF 인증(MD5/HMAC-SHA)·수동 인터페이스(passive-interface) 설정.

지표(불릿):
- 수렴 시간 — 목표 수초 이내 — 링크 다운 후 재수렴까지 측정.
- LSDB 규모 — Area당 LSA 수 관리 — show ip ospf database로 계수.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **캠퍼스·DC 코어 IGP**: 이중화된 캠퍼스·데이터센터 내부를 Area 0 중심으로 설계하고, 규모가 커지면 접속·집선 계층을 별도 Area로 분리해 SPF 부하를 국소화함.
2. **경로 재분배 경계 통제**: ASBR에서 정적·BGP 경로를 OSPF로 재분배할 때 Route-map·Tag로 필터링하고, ABR에서 Summary로 상세 경로 노출을 억제함.
3. **IPv6 이중 스택**: IPv4는 OSPFv2, IPv6는 OSPFv3(또는 OSPFv3 AF)로 병행 운용하고, 두 스택의 Cost·Area 설계를 일치시켜 경로 비대칭을 방지함.

**결론(2줄):**
- 기술사 판단: 단일 AS 내부의 중대규모 이중화 망이면 OSPF로 빠른 수렴과 계층 확장을 확보하고, AS 간 정책 라우팅은 BGP(015 참조)에 위임해야 함.
- 향후 방향: SDN(066 참조)·세그먼트 라우팅 환경에서는 OSPF가 언더레이 IGP로 토폴로지를 제공하고, 중앙 컨트롤러가 그 위에 트래픽 엔지니어링 경로를 얹는 방향으로 진화함.
