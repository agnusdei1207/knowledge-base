# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 네트워크 전체 지도를 라우터끼리 공유하여, 목적지까지의 가장 짧은 경로를 계산하는 **링크 상태(Link-State) 라우팅 프로토콜**입니다.
- **필요성**: RIP 같은 옛날 방식은 '몇 정거장(Hop)'인지만 따지기 때문에 느리고 비효율적입니다. OSPF는 '도로의 속도(Bandwidth)'를 따지고, 장애가 나면 빛의 속도로 우회로를 찾아 대규모 네트워크에 필수적입니다.
- **핵심 직관**: **"모든 라우터가 똑같은 전체 지도를 들고 각자 길 찾기"**.

## 깊이 이해
- **배경 (벨만-포드의 한계 극복)**: RIP는 홉 수 15개가 한계이고 루프(Loop)가 생기기 쉽습니다. OSPF는 **다익스트라(Dijkstra) 알고리즘**을 사용하여 루프 없는 최단 경로를 보장하며, 현재 가장 널리 쓰이는 내부 라우팅 프로토콜(IGP)입니다.
- **작동 원리 (Link-State의 정석)**:
  1.  **LSA (Link State Advertisement)**: "내 주변 링크 상태는 이래!"라고 광고 패킷을 뿌립니다.
  2.  **LSDB (Link State Database)**: 뿌려진 LSA를 모아 라우터마다 똑같은 전체 지도를 완성합니다.
  3.  **SPF (Shortest Path First)**: 완성된 지도 위에서 자신을 주인공으로 최단 경로 트리를 그립니다.
- **Area (영역) 개념**: 지도가 너무 크면 계산하기 힘듭니다. 그래서 영역(Area)을 나눠 관리합니다. 중심인 **Area 0 (Backbone)**을 기준으로 다른 영역들이 꽃잎처럼 붙는 구조입니다.
- **비유 (내비게이션 시스템)**:
  - **RIP**: 옆 차 운전자에게 "서울 가려면 어디로 가요?"라고 묻는 방식. (부정확할 수 있음)
  - **OSPF**: 모든 차가 실시간 전체 지형 정보를 공유하고, 각자 내비게이션으로 최단 경로를 찍는 방식.

## 연결 개념
- **DR/BDR**: 네트워크 안에서 반장(DR)과 부반장(BDR)을 뽑아 중복된 지도 정보를 정리하는 역할.
- **OSPFv3**: IPv6 환경을 지원하기 위해 업그레이드된 OSPF 버전.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 다익스트라(SPF) 알고리즘을 기반으로 모든 노드가 동일한 LSDB를 공유하여 루프가 없는 최적 경로를 산출하는 링크 상태 라우팅 프로토콜임.
> 2. **가치**: 대역폭 기반의 Cost 메트릭을 사용하여 효율적인 트래픽 분산을 지원하며, 계층적 Area 설계를 통해 대규모 망의 확장성을 확보함.
> 3. **판단 포인트**: 빠른 수렴 속도(Convergence)를 위해 Hello/Dead 타이머 및 SPF Throttling 튜닝이 필요하며, IPv6 환경에서는 OSPFv3로의 전환이 필수임.

## Ⅰ. OSPF의 정의 및 기술적 특징
- **정의**: AS(Autonomous System) 내부에서 최단 경로를 선출하기 위해 다익스트라 알고리즘을 사용하는 표준 링크 상태 라우팅 프로토콜.
- **특징**:
  - **빠른 수렴**: 변화가 생긴 부분만 즉시 광고(Incremental Update)하여 장애 복구가 빠름.
  - **계층적 구조**: Area 개념을 도입하여 라우팅 업데이트 범위를 제한하고 부하 경감.
  - **VLSM/CIDR 지원**: 클래스 없는 주소 할당을 완벽히 수용하여 주소 효율성 극대화.
  - **부하 분산**: 비용(Cost)이 같은 다중 경로에 대해 Equal Cost Multi-Path(ECMP) 지원.

## Ⅱ. OSPF의 핵심 동작 메커니즘 3단계

### 1. Neighbor 형성 및 Adjacency 확립
- **Hello 패킷**을 교환하여 이웃을 발견하고, Router-ID, Area-ID, Password 등 조건이 맞으면 인접 관계 형성.

### 2. LSDB(Link State Database) 동기화
- **LSA(Link State Advertisement)** 정보를 Flooding하여 영역 내 모든 라우터가 동일한 토폴로지 지도를 보유.

### 3. SPF 알고리즘 수행 및 라우팅 테이블 반영
- 각 라우터가 자신을 Root로 하여 최단 경로 트리(Shortest Path Tree)를 계산하고, 결과를 라우팅 테이블에 등록.

## Ⅲ. OSPF 계층적 설계 요소 (Area)

| 구성 요소 | 역할 및 설명 |
|:---:|:---|
| **Area 0 (Backbone)** | 중심이 되는 영역. 모든 일반 Area는 Area 0에 물리적으로 연결되어야 함. |
| **Normal Area** | 일반적인 네트워크 영역. Area 0을 통해 다른 영역과 통신. |
| **ABR (Area Border Router)** | 서로 다른 Area를 연결하는 라우터. 경로 요약(Summary) 수행. |
| **ASBR (AS Boundary Router)** | OSPF 외부 망(BGP, Static 등)과 연결되는 라우터. 외부 경로 주입. |
| **Stub Area** | 외부 경로(LSA Type 5)를 차단하여 라우팅 테이블 크기를 줄인 특수 영역. |

## Ⅳ. OSPFv2 (IPv4) vs OSPFv3 (IPv6) 비교

| 비교 항목 | OSPFv2 | OSPFv3 |
|:---:|:---|:---|
| **지원 프로토콜** | IPv4 전용 | IPv6 전용 (AF 확장을 통해 IPv4도 지원 가능) |
| **인증 방식** | 자체 인증 (MD5 등) | IPv6 IPsec 보안 프레임워크 활용 |
| **식별자 (RID)** | 32비트 IPv4 주소 형태 | 여전히 32비트 숫자 (IPv4 주소 형식을 빌림) |
| **인접 관계 형성** | IPv4 서브넷 일치 필요 | 링크-로컬(Link-Local) 주소를 사용하여 서브넷 무관 |

## Ⅴ. 실무적 OSPF 성능 최적화 방안

### 1. Route Summarization (경로 요약)
- ABR이나 ASBR에서 세부 경로를 하나의 큰 대역으로 묶어 전송함으로써 LSDB 크기와 SPF 연산 부하 최소화.
### 2. DR/BDR 선출 최적화
- 멀티액세스(Ethernet) 망에서 불필요한 Adjacency 폭증을 막기 위해 성능이 좋은 라우터를 DR로 우선 선출(Priority 조정).
### 3. SPF Throttling 및 LSA Pacing
- 네트워크 불안정(Flapping) 시 SPF 계산 주기를 동적으로 조절하여 CPU 과부하 방지.

## Ⅵ. 기술사적 통찰: '전체'와 '부분'의 조화
- **가시성의 비용**: 모든 라우터가 전체 지도를 갖는다는 것은 강력한 도달성을 의미하지만, 동시에 큰 연산 부담을 수반함. 따라서 적절한 **Area 분할**과 **Stub 설정**은 기술이 아닌 설계자의 전략적 선택임.
- **언더레이로서의 OSPF**: 현대의 SDN이나 세그먼트 라우팅(SR) 환경에서도 OSPF는 전체 토폴로지 가시성을 제공하는 '언더레이(Underlay) IGP'로서 그 가치가 더욱 공고해지고 있음.
- **결론**: OSPF는 단순한 프로토콜을 넘어, 대규모 인프라의 안정성과 확장성을 지탱하는 가장 신뢰할 수 있는 **"네트워크의 지도 제작자"**임.
