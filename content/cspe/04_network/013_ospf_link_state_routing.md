## 미리 알고가기

- OSPF: 링크 상태 정보를 교환해 각 라우터가 최단 경로 트리를 계산하는 내부 게이트웨이 프로토콜임
- LSA: 라우터가 자신의 링크 상태와 비용을 알리는 광고 메시지임
- LSDB: 라우터가 수집한 링크 상태 정보를 저장한 데이터베이스임
- SPF: LSDB를 기준으로 자신을 루트로 하는 최단 경로 트리를 계산하는 절차임
- Area: OSPF 토폴로지와 LSA 범위를 나눠 관리하는 논리 영역임

## Ⅰ. 개요

- **정의/개념**: OSPF는 같은 자율 시스템 안에서 라우터들이 링크 상태를 공유하고 SPF 계산으로 목적지별 최단 경로를 선택하는 링크 상태 라우팅 프로토콜임
- **배경/필요성**: 홉 수만 보는 단순 경로 선택은 대역폭과 장애 변화를 반영하기 어려우므로 링크 비용과 영역 구조를 반영하는 내부 라우팅 절차가 필요함

## Ⅱ. 특징

- 각 라우터가 같은 Area의 LSDB를 맞춘 뒤 독립적으로 SPF를 계산함
- Cost는 주로 인터페이스 대역폭을 기준으로 산정되며 경로 선택의 메트릭이 됨
- Area 구조는 LSA 전파 범위와 계산 부담을 줄이기 위해 사용함
- OSPFv3는 IPv6 지원을 위해 주소 처리와 LSA 구조가 조정된 버전임

## Ⅲ. 종류 및 비교

| 판단 기준 | 거리 벡터 | 링크 상태 |
|:---|:---|:---|
| 정보 범위 | 인접 라우터가 알려 준 거리와 방향을 사용함 | 링크 상태를 모아 영역 내 토폴로지를 구성함 |
| 계산 방식 | 인접 정보 업데이트로 경로를 갱신함 | LSDB 기반 SPF 계산으로 경로를 산출함 |
| 수렴 특성 | 정보 전파가 단계적으로 진행되어 지연될 수 있음 | 변경 LSA 전파 후 각 라우터가 다시 계산함 |
| 대표 프로토콜 | RIP이 대표적임 | OSPF와 IS-IS가 대표적임 |

> 요약: OSPF는 링크 상태를 공유한 뒤 각 라우터가 같은 지도를 기준으로 경로를 계산하는 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Neighbor | Hello 패킷으로 인접 관계를 맺고 상태 정보를 교환하는 라우터임 |
| LSA | 라우터, 네트워크, 외부 경로 같은 링크 상태를 알리는 단위임 |
| LSDB | 같은 Area 안에서 동일해야 하는 링크 상태 정보 집합임 |
| SPF Tree | LSDB를 입력으로 계산한 최단 경로 트리이며 라우팅 테이블의 근거가 됨 |
| ABR/ASBR | Area 사이 또는 외부 라우팅 도메인과 경로 정보를 연결하는 라우터임 |

```text
+--------+      LSA Flooding      +--------+
|Router A| <--------------------> |Router B|
+--------+                       +--------+
      \          same Area LSDB       /
       +---------- SPF ------------+
```

> 요약: OSPF 구조는 인접 관계, LSA 전파, LSDB 동기화, SPF 계산이 순서대로 연결됨

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 인접형성  | --> | LSA전파  | --> | LSDB동기화 | --> | SPF계산  |
+----------+     +----------+     +----------+     +----------+
```

1. **인접형성**: Hello 패킷으로 이웃을 발견하고 인접 상태를 구성함
2. **LSA전파**: 링크 상태와 Cost 정보를 Area 안에 플러딩함
3. **LSDB동기화**: 라우터들이 같은 Area의 토폴로지 정보를 맞춤
4. **SPF계산**: 각 라우터가 자신을 기준으로 최단 경로 트리를 계산하고 라우팅 테이블에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 캠퍼스나 데이터센터 내부망에서는 Area 0과 하위 Area 경계를 명확히 잡아야 하며 LSA 폭증이 생기지 않도록 Area별 라우터 수, LSA 수, SPF 재계산 횟수로 확인함
2. 이더넷 멀티액세스 구간에서는 네트워크 타입과 DR 우선순위 설정이 장비마다 다르면 인접 관계가 형성되지 않을 수 있으므로 설정값, Neighbor 상태, 수렴 시간을 확인함

## Ⅶ. 결론

OSPF의 판단 기준은 빠른 길이라는 말이 아니라 링크 상태 공유, LSDB 동기화, SPF 계산, Area 경계 설계임.

## 작성 근거(검토용)

- OSPF의 경로 계산은 같은 LSDB와 Cost 기준 SPF 계산으로 한정해 설명함
- RIP 대비는 느림/빠름 단정이 아니라 정보 범위와 계산 방식 차이로 정리함
- 결론은 속도 표현을 배제하고 OSPF의 실제 절차와 설계 기준을 회수함
