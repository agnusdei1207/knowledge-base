## Ⅰ. 개요
- **정의**: 데이터가 발생하는 물리적 장소(사용자 단말, 공장 등) 또는 그와 가장 인접한 네트워크 가장자리(Edge)에서 데이터 연산 및 저장을 수행하는 분산 컴퓨팅 아키텍처임.
- **배경/필요성**: 수많은 IoT 기기로부터 발생하는 방대한 데이터를 모두 중앙 클라우드로 전송 시 발생하는 대역폭 병목, 전송 비용, 응답 지연(Latency) 문제 해결.
- **출제 의도**: 에지 컴퓨팅의 특성(초저지연, 대역폭 절감), 중앙 클라우드와의 상호 보완적 역할 구조 및 통신사 MEC(Mobile Edge Computing) 융합 이해.

## Ⅱ. 구성요소
```text
+-----------------------+              +-----------------------+
|   IoT Devices /       |              |   Central Cloud       |
|   Autonomous Vehicles |              |  (Big Data, Deep AI)  |
+-----------+-----------+              +-----------+-----------+
            | (Raw Data)                           ^
            v                                      | (Filtered/
+-----------------------+                          |  Summary)
|     Edge Node / MEC   |                          |
| (Local Process & AI)  |--------------------------+
+-----------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| IoT Devices | 현실 세계에서 센서나 카메라를 통해 원시 데이터(Raw Data)를 쉼 없이 생성하는 종단 기기 | 현장 직원 |
| Edge Node | 데이터 발생지와 가까운 곳(기지국, 게이트웨이)에 위치하여 즉각적 분석과 제어를 수행하는 소형 서버 | 현장 감독관 |
| Central Cloud | 에지에서 1차 가공되어 전송된 중요 데이터를 장기 보관하고 대규모 심층 학습(AI)을 수행하는 거대 서버 | 본사 기획팀 |
> 요약: 현장 감독(Edge)이 빠른 판단과 잔업을 처리하고, 본사(Cloud)는 핵심 정보만 받아 큰 그림을 그리는 분업 구조임.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 데이터수집|-> | 로컬 분석   |-> | 즉각 제어   |-> | 요약 전송 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **데이터 수집**: 센서, 드론, CCTV 등이 대용량/고빈도의 스트리밍 데이터를 로컬 네트워크를 통해 지속 생성함.
2. **로컬 분석**: 에지 노드(게이트웨이/MEC)가 데이터를 수신하여 실시간 추론(Inference) 알고리즘으로 즉각 분석을 수행함.
3. **즉각 제어**: 분석 결과 이상 상황(예: 불량품 감지, 보행자 출현) 판단 시, 클라우드를 거치지 않고 즉시 설비나 차량에 제어 명령을 내림 (초저지연 응답).
4. **요약 전송**: 단기 데이터는 에지에서 폐기하고, 장기 분석이나 모델 재학습이 필요한 핵심/요약 데이터만 덜어내어 중앙 클라우드로 전송함 (대역폭 절감).
> 요약: 1차 처리는 현장에서 끝내어 골든타임을 확보하고, 클라우드 트래픽 부담을 대폭 감소시키는 체계임.

## Ⅳ. 문제점
- **관리 복잡성**: 지리적으로 광범위하게 수천/수만 개로 흩어진 물리적 에지 노드들에 대한 통합 모니터링, S/W 패치, 보안 관리가 매우 어려움.
- **물리적 보안 취약점**: 클라우드 데이터센터와 달리 에지 장비는 공장 구석이나 도로변 등에 방치되기 쉬워 도난 및 물리적 훼손 위험 큼.
- **한정된 리소스 리스크**: 에지 서버의 연산 능력이 초과하는 예상치 못한 피크 트래픽 발생 시 로컬 처리 지연 및 장애가 유발됨.

## Ⅴ. 개선방안
- **자동화 인프라 적용**: 쿠버네티스(K3s 등) 기반의 경량 컨테이너 기술과 제로 터치 프로비저닝(ZTP)을 통한 배포 및 복구 자동화 (단기).
- **에지 보안 프레임워크**: 장비 부팅 시 펌웨어 무결성을 검증하는 하드웨어 신뢰 루트(TPM) 적용 및 데이터 암호화 (중기).
- **동적 워크로드 오프로딩**: 부하 집중 시 근접한 다른 에지 노드나 중앙 클라우드로 유연하게 연산 태스크를 넘기는(Offloading) 오케스트레이션 연동 (장기).

## Ⅵ. 전망
- 5G 특화망(이음5G) 보급과 결합하여 스마트 팩토리, 원격 수술, 메타버스 등 실시간성(Real-time)이 절대적인 B2B 산업의 핵심 두뇌로 정착됨.
- 향후 개인 정보 보호가 강조됨에 따라, 원본 데이터를 밖으로 내보내지 않고 각 에지에서 학습한 가중치만 클라우드로 공유하는 연합 학습(Federated Learning) 인프라로 고도화될 것임.
