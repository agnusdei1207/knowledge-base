## 미리 알고가기

- RU는 안테나와 무선 신호 처리를 담당하는 무선 장치임
- DU와 CU는 기지국 처리를 분리한 분산 장치와 중앙 장치임
- 프론트홀은 RU와 DU 사이를 잇는 고속 연결 구간임
- RIC는 무선 자원 최적화를 지원하는 지능형 제어 기능임

## Ⅰ. 개요

- **정의/개념**: 오픈랜은 기지국 하드웨어와 소프트웨어를 분리하고 장비 간 인터페이스를 개방형 표준으로 맞춰 여러 벤더 장비를 조합할 수 있게 한 무선 접속망 구조임
- **배경/필요성**: 5G 기지국이 늘어날수록 특정 벤더 종속과 고가 장비 부담이 커지므로, 비용과 협상력 문제를 줄이고 소프트웨어 기반 운영을 확대할 개방형 구조가 필요함

## Ⅱ. 특징

- RU, DU, CU를 분리해 장비와 소프트웨어를 다른 벤더 조합으로 구성할 수 있음
- 개방형 프론트홀과 관리 인터페이스를 통해 벤더 종속을 낮추려 함
- 범용 서버와 가상화 기술을 활용해 RAN 소프트웨어화를 촉진함
- RIC의 표준 인터페이스를 통해 xApp·rApp 기반 무선 자원 제어 정책을 추가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적 폐쇄형 RAN | 오픈랜 |
|:---|:---|:---|
| 장비 구성 | 한 벤더 장비와 소프트웨어를 일체형으로 쓰는 경우가 많음 | RU, DU, CU를 분리해 여러 벤더 조합 구성이 가능함 |
| 인터페이스 | 제조사 내부 규격 의존도가 높음 | 개방형 프론트홀과 관리 인터페이스 사용을 지향함 |
| 운영 유연성 | 기능 변경과 확장 시 벤더 로드맵 의존이 큼 | 가상화와 소프트웨어 업데이트를 통한 유연성이 높음 |
| 도입 난점 | 상호운용성 검증 범위가 상대적으로 좁음 | 다중 벤더 조합에서 성능 검증과 책임 분담이 더 어려움 |

> 요약: 오픈랜은 자유도가 높아지는 대신 상호운용성과 통합 책임 관리가 더 중요해지는 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| O-RU | 안테나와 무선 송수신을 담당하며 프론트홀 표준으로 DU와 연결됨 |
| O-DU | 실시간 무선 처리를 담당하며 엣지 또는 지역 거점에 배치되기 쉬움 |
| O-CU | 제어 기능을 상위에서 처리하며 다수 DU를 통합 제어함 |
| SMO와 RIC | 운영 자동화와 무선 자원 최적화를 담당하는 관리 계층임 |
| 범용 하드웨어와 가상화 | 무선 기능을 소프트웨어 단위로 배치·업그레이드하는 기반임 |

```text
+--------+     +-------------+     +-------------+     +----------------+
| O-RU    | --> | O-DU        | --> | O-CU        | --> | SMO·RIC         |
+--------+     +-------------+     +-------------+     +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| 기능 분리 설계   | --> | 인터페이스 연동    | --> | 성능·호환성 검증    | --> | 운영 자동화 적용   |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **기능 분리 설계**: RU, DU, CU 기능 경계를 정하고 배치 위치를 설계함
2. **인터페이스 연동**: 개방형 프론트홀과 관리 인터페이스로 벤더 장비를 연결함
3. **성능과 호환성 검증**: 지연 시간, 동기화, 처리량을 시험해 실제 무선 품질을 확인함
4. **운영 자동화 적용**: RIC와 운영 플랫폼으로 자원 제어 정책과 자동화 규칙을 적용함

## Ⅵ. 실무 적용 및 유의점

1. 다중 벤더 RU·DU·CU를 조합할 때는 프론트홀 호환성과 실시간 처리 지연이 요구 범위를 벗어날 수 있으므로 상호운용성 시험과 기준 성능선을 정하고 패킷 지연 편차와 무선 처리량으로 확인함
2. RIC 기반 자동화를 도입하는 환경에서는 개방성이 곧 운영 단순화를 뜻하지 않으므로 앱 배포 권한과 성능 검증 절차를 함께 설계하고 xApp 배포 실패율과 최적화 정책 반영 시간을 기준으로 확인함

## Ⅶ. 결론

오픈랜의 가치는 벤더 종속을 줄이고 RAN 소프트웨어화를 여는 데 있으므로 개방형 인터페이스만큼 상호운용성 검증 역량이 중요함.
