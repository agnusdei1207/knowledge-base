# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: DHCP는 단말이 접속할 때 IP 주소와 서브넷 마스크·게이트웨이·DNS를 자동으로 임대(Lease)해 주는 UDP 기반 프로토콜임 (IP는 004, MAC은 007 참조).
- **왜 필요한가**: 수백 대 단말에 관리자가 일일이 고정 IP를 넣는 것은 불가능하고 충돌 위험이 크므로, 중앙 서버가 주소 풀을 자동 배분·회수해야 함.
- **핵심 직관**: 식당에 들어서면 종업원이 "빈자리(IP)는 5번, 메뉴판(DNS)과 출구(게이트웨이)는 저기"라고 한 번에 안내해 주는 것과 같음.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안(Ⅰ~Ⅵ·표)에 나오는 것들을 미리 풀어 둔 것임. 최상위 키워드는 **동적 IP 임대(DORA)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| DORA | Discover-Offer-Request-ACK 4단계 할당 절차 | 손님-프론트의 객실 배정 4마디 대화 |
| Discover | 단말이 "IP 줄 서버 있나요?" 브로드캐스트 | 로비에서 "빈방 있어요?" 외침 |
| Offer | 서버가 "이 IP 어때요?" 제안 | 프론트가 "203호 어떠세요?" |
| Request | 단말이 "그 IP 쓸게요" 확정 요청 | "203호로 할게요" |
| ACK | 서버가 옵션까지 담아 최종 승인 | 키·조식권·체크아웃시간 전달 |
| Lease Time | 할당 IP의 유효 임대 시간 | 체크아웃 시각 |
| T1 (50%) | 임대 절반 시점, 기존 서버에 유니캐스트 갱신 | 반나절 지나 "연장할게요"(직통) |
| T2 (87.5%) | 응답 없을 때 아무 서버에 브로드캐스트 재바인딩 | 직통 안 되면 "아무나 연장" |
| Relay Agent | 다른 대역 서버로 브로드캐스트를 유니캐스트 중계 | 층별 안내데스크가 본사로 연결 |
| ip helper-address | Relay를 설정하는 라우터 명령 | 중계 전화번호 등록 |
| Option 필드 | IP 외 부가정보(DNS·TFTP 등) 전달 슬롯 | 안내문 부록 |
| DHCP Snooping | 스위치가 신뢰 포트의 Offer만 허용 | 정식 직원 안내만 인정 |
| Rogue DHCP | 사내에 끼어든 가짜 DHCP 서버 | 사기꾼이 가짜 방 배정 |
| SLAAC | IPv6의 서버 없는 자동 주소 생성 방식 | 스스로 자리 만들기 |

## 깊이 이해
- **배경·문제의식**: 과거 고정 IP는 노트북·모바일 이동성이 커지며 접속마다 수동 설정해야 하는 부담과 충돌을 낳아, 자동 할당 체계가 필요했음.
- **작동 원리(DORA 4단계)**: Discover(단말이 서버 탐색 브로드캐스트) → Offer(서버가 후보 IP 제안) → Request(단말이 특정 IP 확정 요청) → ACK(서버가 게이트웨이·DNS 옵션까지 담아 승인). 단말은 아직 IP가 없어 각 단계가 대부분 브로드캐스트로 오감.
- **비유**: 호텔 프론트(서버)가 손님(PC)에게 빈 객실(IP) 키를 빌려주며 체크아웃 시간(Lease Time)을 정해 주는 임대 시스템임.
- **구체 예시**: 카페 와이파이에 폰을 연결하면 폰이 Discover를 뿌리고, 매장 라우터가 사설 IP(예: 172.16.0.50)를 즉시 임대해 인터넷을 붙여 줌.
- **흔한 오해·주의점**: IP는 영구 부여가 아니라 '임대'임. Lease가 끝나기 전 T1·T2 시점에 갱신하지 못하면 IP가 회수됨.

## 연결 개념
- 서브넷 마스크·게이트웨이·DNS — DHCP가 IP와 묶어 패키지로 배포하는 필수 파라미터.
- ARP (008 참조) — 서버가 할당 전 해당 IP를 Ping/ARP로 점검해 충돌을 예방.
- BOOTP — DHCP의 전신으로 디스크리스 부팅용이었으나 DHCP에 흡수됨.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DHCP는 IP와 네트워크 구성 파라미터를 호스트에 동적으로 임대하는 UDP(67/68) 기반 프로토콜임.
> 2. **가치**: 대규모 이동성 환경에서 IP 할당을 자동화해 관리 개입을 없애고, 충돌 방지와 주소 재사용률을 극대화함.
> 3. **판단**: 브로드캐스트 DORA 특성상 Rogue DHCP·Starvation에 취약하므로, DHCP Snooping과 Relay(ip helper-address) 구조를 설계에 반드시 포함해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DORA 동작 프로세스 | Discover-Offer-Request-ACK 흐름과 브로드캐스트 특성 | 4단계를 나열만 하고 L2/L3 주소 특성 누락 |
| 임대·갱신 메커니즘 | T1(50% 유니캐스트)·T2(87.5% 브로드캐스트) 갱신 | 영구 할당으로 오인하게 서술 |
| 실무 아키텍처·보안 | Relay Agent(ip helper)와 DHCP Snooping 통제 | 소규모 홈 네트워크 관점으로만 서술 |

> 요약: DORA 기본 위에, 기업망은 "다른 대역 서버와 어떻게 통신(Relay)"과 "가짜 서버를 어떻게 차단(Snooping)"으로 방점을 찍어야 함.

## Ⅰ. 개요 및 필요성

- 정의: 클라이언트에 IP·서브넷 마스크·게이트웨이·DNS를 동적 할당하는 UDP 기반 프로토콜임.
- 배경: 이동형 기기 급증으로 수동 고정 IP는 관리 오버헤드와 충돌이 한계에 달함.
- 필요성: 중앙 주소 풀로 미사용 IP를 회수·재사용하고 대규모 망의 제로터치 프로비저닝을 지원함.

---

## Ⅱ. 구조 및 구성요소

구조도(선형):

```text
Client(UDP 68) -> Discover 브로드캐스트 -> DHCP Server(UDP 67)
  Server -> Offer(후보 IP) -> Client -> Request(확정) -> Server -> ACK(옵션 포함)
  다른 대역이면: Client -> Relay Agent(ip helper) -> 유니캐스트 중계 -> 중앙 Server
```

| 구성요소 | 역할 | 주요 파라미터 |
|:---|:---|:---|
| DHCP Server | 주소 풀·임대 상태 관리 | IP 대역, Exclude, Lease Time |
| DHCP Client | 서버 탐색 및 할당 요청 | 자신의 MAC 기반 요청 |
| Relay Agent | 브로드캐스트를 유니캐스트로 원격 서버 중계 | ip helper-address |
| 임대 타이머 | 할당 주소 유효기간 관리 | T1(50%), T2(87.5%) |

> 요약: DORA를 수행하는 클라이언트-서버 모델이며, 엔터프라이즈는 L3 장비의 Relay Agent가 중앙 서버를 통합 관리함.

---

## Ⅲ. 동작원리 및 흐름도

흐름도(선형):

```text
DORA 4단계 -> IP 획득(Lease Time 시작)
  -> T1(50%) 기존 서버에 유니캐스트 갱신 -> 성공 시 Lease 리셋
  -> T2(87.5%) 응답 없으면 전체 서버에 브로드캐스트 재바인딩 -> 만료 시 IP 반납
```

- 1단계: 단말이 출발지 0.0.0.0, 목적지 255.255.255.255로 Discover를 브로드캐스트함(IP가 없어 유니캐스트 불가).
- 2단계: 서버가 후보 IP를 담아 Offer를 회신함(브로드캐스트 또는 유니캐스트).
- 3단계: 단말이 선택한 IP를 명시해 Request를 브로드캐스트함(다른 서버에 미채택 통보 겸용).
- 4단계: 서버가 게이트웨이·DNS 등 옵션을 담아 ACK로 확정하고, 이후 T1·T2 시점에 갱신이 진행됨.

> 요약: 단말이 IP 없는 상태라 L3 유니캐스트가 불가하여 DORA는 브로드캐스트에 의존하며, 갱신 단계에서만 유니캐스트가 가능함.

---

## Ⅳ. 특징

- 중앙 집중 관리: 게이트웨이·DNS 변경을 서버 한 곳만 수정하면 전 클라이언트에 반영되나, 서버 장애 시 파급이 커 SPOF가 됨.
- 주소 회수 최적화: Lease Time을 용도별로 조절(무선 2시간 등)해 유동 인구가 많은 곳의 IP 회수율을 높임.
- 옵션 확장성: Option 43(WLC IP)·Option 150(TFTP IP) 등으로 AP·IP폰의 자동 프로비저닝까지 전달함.
- 브로드캐스트 의존: 초기 할당이 브로드캐스트라 세그먼트를 넘으려면 Relay가 필수이고, 이 특성이 보안 취약점의 근원이 됨.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 고정 할당(Static) | 동적 할당(DHCP) |
|:---|:---|:---|
| 적용 대상 | 인프라 서버·라우터·DB | 사무실 PC·모바일·IoT |
| 충돌 위험 | 휴먼 에러 시 충돌 높음 | 서버가 사전 점검 후 할당해 낮음 |
| 관리 편의 | 대수 늘면 수동 관리 부담 | 100대 이상도 자동 관리 |
| 보안 통제 | IP-MAC 바인딩 용이 | Rogue DHCP 등 스푸핑 취약 |

> 요약: 고정 IP는 안정성이 중요한 서버 구역에, DHCP는 유연성이 필요한 사용자 구역에 적용하는 것이 아키텍처 원칙임.

리스크·대응(불릿):
- Rogue DHCP — 사내 공유기 오접속·해커의 가짜 서버 — 서버 방향 업링크만 Trust로 두는 DHCP Snooping.
- DHCP Starvation — MAC 변조로 주소 풀 고갈 — 포트별 Port Security로 학습 MAC 수 제한.
- 서버 SPOF — 서버 다운 시 신규 접속·갱신 실패 — DHCP Failover(Active-Standby/Active-Active)로 Lease DB 동기화.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **DHCP Snooping 차단**: 액세스 스위치의 서버 방향 업링크만 Trust, 나머지 단말 포트는 Untrust로 지정해 가짜 Offer를 원천 차단.
2. **IP Helper 아키텍처**: 지사마다 서버를 두지 않고 지사 L3 스위치에 ip helper-address를 설정해 본사 중앙 서버로 브로드캐스트를 유니캐스트 중계.
3. **용도별 Lease 튜닝**: 고정 좌석 유선 PC는 8일, 카페·회의실 무선 단말은 2시간으로 설정해 주소 고갈을 예방.

**결론(2줄):**
- 기술사 판단: 소규모 단일 서브넷이면 라우터 내장 DHCP로 충분하나, 다중 대역 기업망이면 Relay 중앙화와 Snooping 방어를 함께 설계해야 함.
- 향후 방향: IPv6에서는 SLAAC 자동 주소 생성이 주류가 되고, DHCPv6는 DNS 등 부가 옵션만 전달하는 보완재로 역할이 축소·전환되고 있음.
