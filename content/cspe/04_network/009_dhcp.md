## 미리 알고가기

- DHCP: 단말에 IP 주소와 네트워크 옵션을 자동 임대하는 프로토콜임
- DORA: Discover, Offer, Request, Acknowledge로 이어지는 IPv4 DHCP 기본 절차임
- Lease Time: 단말이 할당받은 주소를 사용할 수 있는 임대 시간임
- DHCP Relay: 서로 다른 서브넷의 클라이언트와 DHCP 서버 사이 메시지를 중계하는 기능임

## Ⅰ. 개요

- **정의/개념**: DHCP는 네트워크에 접속한 단말에 IP 주소, 서브넷 마스크, 기본 게이트웨이, DNS 같은 설정 값을 자동으로 임대하는 프로토콜임
- **배경/필요성**: 단말 수가 많은 환경에서 수동 주소 설정은 중복, 오입력, 회수 누락을 만들기 때문에 중앙 임대 관리 절차가 필요함

## Ⅱ. 특징

- DHCP는 주소를 영구 할당하지 않고 임대 시간 기준으로 배정하고 갱신함
- 초기 Discover는 서버 위치를 모를 수 있어 브로드캐스트로 시작함
- Relay Agent를 쓰면 중앙 DHCP 서버가 여러 서브넷의 주소를 관리함
- 인증 없는 DHCP 서버가 잘못된 게이트웨이와 DNS를 배포할 수 있어 L2 통제가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 설정 | DHCP |
|:---|:---|:---|
| 주소 배정 | 관리자가 단말별로 직접 입력함 | 서버가 주소 풀에서 임대함 |
| 변경 대응 | 주소 변경 시 단말마다 수정해야 함 | 서버 옵션 변경으로 일괄 반영함 |
| 오류 유형 | 오입력과 중복 주소가 발생하기 쉬움 | 주소 풀 고갈과 위조 서버를 통제해야 함 |
| 적합 대상 | 고정 서버, 네트워크 장비 관리 주소에 적합함 | 사용자 단말, 무선, 임시 접속 장비에 적합함 |

> 요약: DHCP는 단말 주소 운영을 임대 절차로 중앙 관리하지만 위조 서버와 주소 풀 상태를 함께 통제해야 함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DHCP Client | 주소와 옵션을 요청하는 단말이며 초기에는 자신의 IP를 모를 수 있음 |
| DHCP Server | 주소 풀, 임대 시간, 게이트웨이, DNS 옵션을 관리하고 응답함 |
| DHCP Relay | 브로드캐스트가 라우터를 넘지 못하는 문제를 해결하기 위해 서버로 메시지를 중계함 |
| Address Pool | 임대 가능한 주소 범위이며 예약 주소와 제외 주소를 함께 관리해야 함 |

```text
+--------+   Discover/Request   +-------+   unicast   +--------+
| Client | -------------------> | Relay | ----------> | Server |
+--------+ <------------------- +-------+ <---------- +--------+
          Offer/Ack
```

> 요약: DHCP는 클라이언트 요청, 서버 임대, 릴레이 중계를 통해 서브넷을 넘어 주소 설정을 자동화함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| Discover | --> | Offer    | --> | Request  | --> | Ack      |
+----------+     +----------+     +----------+     +----------+
```

1. **Discover**: 클라이언트가 사용 가능한 DHCP 서버를 찾음
2. **Offer**: 서버가 할당 가능한 주소와 옵션을 제안함
3. **Request**: 클라이언트가 선택한 서버와 주소를 요청함
4. **Ack**: 서버가 임대를 확정하고 임대 시간과 옵션을 전달함

## Ⅵ. 실무 적용 및 유의점

1. 사용자망에서는 Rogue DHCP가 잘못된 DNS와 게이트웨이를 배포할 수 있으므로 DHCP Snooping으로 신뢰 포트를 제한하고 차단 로그와 클라이언트 게이트웨이 값을 확인함
2. 무선망이나 VDI처럼 접속 변동이 큰 환경에서는 Lease Time이 너무 길면 주소 풀이 고갈되므로 접속 패턴에 맞게 조정하고 풀 사용률과 임대 실패 건수로 확인함

## Ⅶ. 결론

DHCP는 주소 설정 자동화가 아니라 주소 임대, 옵션 배포, 풀 회수를 중앙에서 통제하는 운영 절차임.

## 작성 근거(검토용)

- DHCP의 판단 단어는 "자동화"로 끝나면 부족하므로 임대, 옵션, 회수, 위조 서버 통제까지 답안 축으로 잡음
- DORA는 절차 자체가 답안 흐름을 결정하므로 단계별 동작을 짧게 두고 구성요소와 중복하지 않게 작성함
- 결론은 관리 편의가 아니라 중앙 임대 통제라는 역할을 회수함
