## Ⅰ. 개요
- **정의**: IP 주소 대신 콘텐츠 이름으로 데이터를 요청·전달하는 미래 인터넷 아키텍처임
- **배경/필요성**: 현재 IP 기반 통신은 호스트 위치에 종속되어 콘텐츠 중심 트래픽에 비효율적임
- **비유**: 도서관에서 책꽂이 위치가 아니라 책 제목만으로 원하는 책을 찾는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ICN 계열 미래 네트워크 이해 | Interest/Data 패킷 구조·CS/PIT/FIB | IP 네트워크와의 구조적 차이 명시 필요 |

> 요약: 콘텐츠 이름 기반으로 데이터를 요청·캐싱·전달하는 미래 인터넷 아키텍처임

## Ⅱ. 구성요소
```text
[Consumer] --Interest--> [NDN Router] --Interest--> [Producer]
                              |
                     +--------+--------+
                     |        |        |
                    [CS]    [PIT]    [FIB]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CS (Content Store) | 라우터 내 데이터 캐시로 동일 요청 시 즉시 응답 | 도서관 대출 데스크 |
| PIT (Pending Interest Table) | 아직 응답받지 못한 Interest의 유입 인터페이스 기록 | 주문 대기 명부 |
| FIB (Forwarding Info Base) | 이름 접두사별 다음 홉 정보를 저장 | 이정표 |
| Interest/Data 패킷 | 요청(Interest)과 응답(Data)으로 구성된 NDN 통신 단위 | 질문지와 답변지 |

> 요약: CS·PIT·FIB 3대 자료구조로 이름 기반 라우팅과 인네트워크 캐싱을 수행함

## Ⅲ. 절차
```text
Interest 발행 -> PIT/CS 조회 -> 포워딩/캐시 응답 -> Data 역경로 전달
```
- 1단계: Interest 발행 — 소비자가 콘텐츠 이름을 담은 Interest 패킷 전송
- 2단계: PIT/CS 조회 — 라우터가 CS에 캐시 존재 시 즉시 응답, 없으면 PIT에 기록
- 3단계: 포워딩 — FIB를 참조하여 Interest를 생산자 방향으로 전달
- 4단계: Data 역경로 전달 — 생산자 응답 Data가 PIT 기록을 따라 소비자에게 역전달

> 요약: Interest-PIT/CS-FIB-Data 역경로의 4단계로 이름 기반 통신을 완료함

## Ⅳ. 문제점
- 네이밍 확장성: 계층적 이름 공간의 글로벌 규모 관리·해석 체계가 미확립임
- 캐시 프라이버시: CS 캐시 타이밍 분석으로 사용자 관심사가 노출될 수 있음
- IP 호환성: 기존 IP 인프라와의 점진적 전환 경로가 부재함

> 요약: 네이밍 확장성·캐시 프라이버시·IP 호환이 NDN 실용화의 과제임

## Ⅴ. 개선방안
1. 단기: 도메인별 네이밍 가이드라인 수립으로 이름 체계 표준화 추진
2. 중기: 캐시 랜덤화·접근제어 암호화로 타이밍 공격 방어
3. 장기: NDN-over-IP 오버레이로 기존 인프라 위 점진적 전환 경로 제공

> 요약: 네이밍 표준화·캐시 보안·오버레이 전환으로 NDN 실용화를 촉진함

## Ⅵ. 전망
- 발전 방향: IoT·차량 네트워크 등 콘텐츠 중심 도메인에서 우선 적용 확대
- 기술사적 판단: 범용 IP 대체보다 특정 도메인 최적화 아키텍처로 공존할 것임
- 기술사 제언: IoT·엣지 컴퓨팅 시나리오 중심의 실증 사업 추진이 필요함
