## 미리 알고가기

- NMS는 여러 네트워크 장비를 중앙에서 감시하고 운영하는 관리 플랫폼임
- FCAPS는 장애, 구성, 회계, 성능, 보안을 묶어 네트워크 관리 기능을 설명하는 틀임
- 디스커버리는 망 안의 장비와 연결 관계를 자동으로 찾아내는 기능임
- 구성 백업은 장비 설정값을 주기적으로 저장해 변경 추적과 복구에 쓰는 기능임

## Ⅰ. 개요

- **정의/개념**: NMS는 장비 발견, 상태 수집, 성능 분석, 구성 이력, 경보 처리를 한곳에서 수행하는 중앙 네트워크 운영 시스템임
- **배경/필요성**: 장비 수가 많아질수록 개별 접속에 의존한 운영은 장애 탐지와 변경 추적과 용량 관리가 모두 느려지므로 중앙 관리 체계가 필요함

## Ⅱ. 특징

- 장비 상태와 링크 관계와 구성 이력을 한 화면에서 볼 수 있음
- 성능 수집과 장애 경보와 변경 기록을 묶어 운영 흐름을 단순하게 만듦
- 권한 분리와 감사 추적을 지원해 운영 통제를 강화함
- 자동화 도구와 연계하면 반복 작업과 장애 대응 시간을 줄일 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 운영 | NMS | SDN 컨트롤러 |
|:---|:---|:---|:---|
| 관리 방식 | 장비별 접속과 개별 확인에 의존함 | 중앙 화면과 경보 체계로 운영함 | 중앙 제어 평면이 경로와 정책을 직접 반영함 |
| 주된 목적 | 점검과 즉시 조치 | 감시, 기록, 보고, 운영 자동화 | 네트워크 정책 제어와 프로그래밍 |
| 상태 가시성 | 운영자 경험에 크게 좌우됨 | 장비와 링크 상태를 체계적으로 축적함 | 제어 대상 영역은 깊게 보지만 범위가 제한될 수 있음 |
| 적합한 환경 | 소규모 망 | 일반 기업망과 통신망 운영 | 가상화·프로그램 제어가 강한 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 디스커버리와 인벤토리 | 장비와 인터페이스와 연결 관계를 찾아 자산 목록으로 정리함 |
| 성능 수집기 | 사용률과 오류와 지연 같은 지표를 모아 추세를 만듦 |
| 이벤트와 경보 엔진 | 장애와 임계치 초과를 감지해 우선순위별로 통지함 |
| 구성 관리 | 설정 백업과 변경 비교와 복구 절차를 지원함 |
| 연계 모듈 | 티켓 시스템과 자동화 도구와 보고 체계를 연결함 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 장비 발견      | -> | 상태·성능 수집 | -> | 경보·분석      | -> | 변경·복구 관리 |
+-------------+    +-------------+    +-------------+    +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 장비 등록      | -> | 주기 수집      | -> | 이상 감지      | -> | 원인 분석      | -> | 조치 기록      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **장비 등록**: 디스커버리로 장비와 링크를 인벤토리에 올림
2. **주기 수집**: 상태와 성능과 구성 정보를 계속 모음
3. **이상 감지**: 임계치 초과나 다운 이벤트를 경보로 변환함
4. **원인 분석**: 연결 관계와 최근 변경 이력을 함께 보고 원인을 좁힘
5. **조치 기록**: 복구와 설정 변경 내용을 다시 남겨 다음 분석에 활용함

## Ⅵ. 실무 적용 및 유의점

1. 지점과 장비가 많은 기업망은 NMS가 필수지만 토폴로지와 인벤토리가 오래되면 경보 상관 분석이 틀어지므로 자동 발견 주기와 구성 백업 주기를 함께 운영하고 경보 정확도와 복구 시간을 확인해야 함
2. 경보를 과하게 세분하면 운영자가 중요한 장애를 놓치기 쉬우므로 서비스 영향이 큰 항목부터 임계치를 정하고 불필요한 경보 비율과 중복 티켓 발생률을 계속 줄여야 함

## Ⅶ. 결론

NMS의 가치는 화면을 예쁘게 만드는 데 있지 않고 상태 수집과 경보와 변경 이력을 연결해 운영 판단을 빠르게 만드는 데 있음
