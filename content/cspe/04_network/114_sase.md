## 미리 알고가기

- SD-WAN은 애플리케이션 정책과 회선 품질에 따라 지사 트래픽 경로를 선택하는 광역망 기술임
- CASB는 사용자와 클라우드 서비스 사이에서 데이터와 행위를 통제하는 보안 서비스임
- SWG는 웹 접속을 검사하고 차단하는 보안 게이트웨이임
- PoP는 사용자가 가까운 위치에서 서비스를 받도록 둔 접속 거점임

## Ⅰ. 개요

- **정의/개념**: SASE는 네트워크 연결 기능과 보안 기능을 클라우드 PoP에서 통합 제공해 사용자와 지사와 애플리케이션을 같은 정책으로 연결하는 아키텍처임
- **배경/필요성**: SaaS와 원격 근무가 늘자 지사 트래픽을 본사로 되돌려 검사하는 구조는 지연과 운영 복잡도를 키우므로, 가까운 엣지에서 바로 연결하고 바로 검사할 통합 구조가 필요해짐

## Ⅱ. 특징

- 네트워크와 보안을 따로 쌓지 않고 하나의 정책 흐름으로 묶음
- 중앙 정책 엔진이 사용자와 애플리케이션 속성을 기준으로 각 PoP에 정책을 배포함
- 본사 백홀 구간을 줄여 SaaS와 인터넷 접속 지연을 줄일 수 있음
- PoP 품질과 서비스 통합 수준이 낮으면 기대한 단순화가 나오지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 본사 집중형 구조 | SASE |
|:---|:---|:---|
| 트래픽 경로 | 지사 트래픽을 본사로 모아 검사함 | 가까운 PoP에서 바로 연결하고 검사함 |
| 정책 적용 | 장비별로 정책이 흩어지기 쉬움 | 사용자와 애플리케이션 기준으로 통합함 |
| 확장 방식 | 사업장별 회선과 보안 장비를 증설함 | 사용자·지사를 PoP에 연결하고 서비스 용량을 확장함 |
| 적용 환경 | 본사와 고정 사업장 중심 트래픽 | 분산 지사와 SaaS 중심 트래픽 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자·지사 엣지 | 접속을 시작하고 회선 품질을 측정함 |
| SD-WAN 기능 | 경로를 선택하고 품질 기반 분산을 수행함 |
| 클라우드 PoP | 가까운 위치에서 보안 검사와 연결 중계를 제공함 |
| 보안 서비스 묶음 | CASB, SWG, ZTNA 같은 기능을 제공함 |
| 정책 엔진 | 사용자와 기기와 앱 기준으로 정책을 통합함 |

```text
+------------+    최적 경로 선택    +-------------+    보안 검사    +-------------+
| 사용자·지사   | -----------------> | SASE PoP     | -------------> | SaaS·내부 앱   |
+------------+                    +-------------+                +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[사용자 접속] -> [가까운 PoP 선택] -> [정책 검사] -> [최적 경로 전달] -> [지속 모니터링]
```

1. **사용자 접속**: 사용자나 지사 장비가 서비스 접속을 시작함
2. **가까운 PoP 선택**: 품질이 좋은 엣지 거점으로 연결함
3. **정책 검사**: 신원과 기기와 서비스 조건을 함께 확인함
4. **최적 경로 전달**: 허가된 트래픽을 SaaS나 내부 앱으로 전달함
5. **지속 모니터링**: 품질과 보안 이벤트를 계속 수집함

## Ⅵ. 실무 적용 및 유의점

1. SaaS 사용이 많은 기업과 분산 지사는 가까운 PoP에서 트래픽을 검사해 본사 백홀을 줄이며, PoP가 사용자와 멀면 전송 지연이 증가하므로 사용자별 PoP 응답 시간, 접속 지연, 패킷 손실률, 우회 경로 비율을 확인함
2. 기존 방화벽 정책과 새 클라우드 정책이 따로 놀면 운영이 더 복잡해지므로 사용자·애플리케이션 기준으로 정책을 다시 정리하고 중복 정책 건수와 예외 규칙 증가 추이를 함께 봐야 함

## Ⅶ. 결론

SASE의 가치는 기능 이름을 모으는 데 있지 않고 네트워크 경로와 보안 정책을 사용자와 애플리케이션 기준으로 같은 흐름에 올려두는 데 있음.
