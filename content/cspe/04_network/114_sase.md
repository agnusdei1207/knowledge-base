# 📖 【암기용】 개념 완전 이해

> 목적: SASE를 네트워크와 보안을 클라우드 엣지에서 통합 제공하는 구조로 이해하게 만든다.

## 한눈에
- **개요**: SASE는 SD-WAN과 보안 서비스(CASB, SWG, ZTNA, FWaaS)를 클라우드 PoP에서 통합하는 아키텍처이다.
- **왜 필요한가**: 사용자는 지사, 재택, 모바일, 클라우드에 분산되고 트래픽은 데이터센터를 경유하지 않는다.
- **핵심 직관**: 모든 차량을 본사 톨게이트로 보내지 않고, 가까운 지역 검문소에서 경로와 보안 검사를 동시에 처리하는 방식이다.

## 깊이 이해
- **배경·문제의식**: MPLS와 중앙 보안 장비 중심 구조는 SaaS·클라우드 트래픽을 우회 경로로 보내 지연과 정책 불일치를 만든다.
- **작동 원리**: 지사 CPE와 사용자 에이전트가 가까운 SASE PoP에 연결되고, PoP는 SD-WAN 라우팅, SWG, CASB, ZTNA, DLP 정책을 통합 적용한다.
- **비유**: 택배 허브를 하나만 쓰지 않고 지역 물류센터에서 분류, 검사, 배송을 함께 처리하는 구조와 같다.
- **구체 예시**: 해외 지사는 SD-WAN으로 가까운 PoP에 접속하고, 사용자는 ZTNA로 업무 앱에 접근하며, SaaS 업로드는 CASB DLP 정책으로 검사한다.
- **흔한 오해·주의점**: SASE는 제품 하나가 아니라 네트워크 경로와 보안 정책을 클라우드 엣지로 통합하는 운영 모델이다.

## 연결 개념
- SD-WAN - 지사 트래픽 경로 선택과 회선 이중화
- SSE - SASE에서 네트워크 기능을 제외한 보안 서비스 묶음
- CASB/SWG/ZTNA - SASE의 주요 보안 기능

# 📝 【답안용】 시험 답안 템플릿

> 목적: SASE 답안은 약어 나열이 아니라 네트워크 경로 최적화와 보안 정책 집행 위치를 함께 설명한다.
> 핵심: SD-WAN, SWG, CASB, ZTNA, FWaaS가 클라우드 PoP에서 어떤 순서로 통제하는지 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SASE는 분산 사용자와 클라우드 자원에 대해 네트워크 연결과 보안 검사를 클라우드 엣지에서 통합 제공하는 구조이다.
> 2. **가치**: 지사 백홀을 줄이고, SaaS·웹·사내 앱 접근에 동일한 사용자·단말·데이터 정책을 적용한다.
> 3. **판단 포인트**: PoP 위치, SD-WAN 품질, CASB·SWG·ZTNA 통합 수준, 로그 통합성을 기준으로 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SASE 구성요소 이해 확인 | SD-WAN, SWG, CASB, ZTNA, FWaaS, DLP | 보안 기능만 쓰고 네트워크 기능 누락 |
| 아키텍처 전환 판단 확인 | 데이터센터 백홀 축소, PoP 기반 정책 집행 | 클라우드 제품명 나열로 끝냄 |
| 운영 지표 제시 확인 | p95 지연, 터널 가용성, DLP 탐지, 로그 수집 | 품질·감사 지표 없이 효과만 서술 |

> 요약: SASE는 네트워크와 보안을 같은 정책면에서 운영하는 통합 엣지 아키텍처이다.

## Ⅰ. 개요 및 필요성

- 개요: 네트워크·보안 통합 엣지
- 배경: SaaS·클라우드·재택 트래픽이 데이터센터 경계를 우회함.
- 필요성: SD-WAN 경로 제어와 SWG·CASB·ZTNA 정책을 동일 PoP에서 적용해야 함.
- 판단 기준: 지사 수, SaaS 비중, 해외 사용자 지연, 보안 로그 통합 요구를 함께 검토함.

## Ⅱ. 구조 및 구성요소

```text
User/Branch -> SASE PoP -> SD-WAN Routing
                         -> SWG/CASB/DLP Inspection
                         -> ZTNA/FWaaS Policy
                         -> SaaS/IaaS/Private App
                         +-> SIEM/SOAR Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SD-WAN | 인터넷, LTE, MPLS 회선의 경로를 선택 | SLA, jitter, packet loss 기반 라우팅 |
| SWG | 웹 접속, URL, 악성코드, SSL 검사 | TLS 복호화 예외 정책 필요 |
| CASB | SaaS 사용, API, DLP, Shadow IT 통제 | API 방식과 Proxy 방식 병행 |
| ZTNA | 사내 앱 접근을 사용자·단말 기준으로 허가 | VPN 대체 또는 공존 설계 |
| FWaaS/DLP | 방화벽 정책과 데이터 유출 검사를 제공 | 정책 중복과 우선순위 관리 필요 |

> 요약: SASE는 SD-WAN 경로 제어와 보안 기능을 PoP에서 묶어 사용자와 앱 사이의 공통 통제 지점을 만든다.

## Ⅲ. 동작원리 및 흐름도

```text
트래픽 발생 -> 가까운 PoP 접속 -> 사용자/단말 식별
-> 경로 선택 -> 웹/SaaS/앱별 정책 검사 -> 목적지 전달 -> 로그 전송
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자 에이전트 또는 지사 CPE가 PoP에 연결 | 터널 상태, PoP RTT, 인증 성공 |
| 2 | SD-WAN이 회선 품질과 목적지를 기준으로 경로 선택 | packet loss 1% 이하, jitter 30ms 이하 |
| 3 | SWG/CASB가 웹·SaaS 트래픽을 검사 | URL 분류, DLP 룰, 악성코드 탐지 |
| 4 | ZTNA가 사내 앱 접근을 정책으로 허가 | IdP, MFA, device posture |
| 5 | 로그가 SIEM/SOAR로 전달되어 상관분석 | 사용자 ID, 앱 ID, 정책 결과 |

> 요약: SASE는 가까운 PoP에서 경로를 결정하고, 보안 검사를 수행한 뒤, 통합 로그를 남긴다.

> 요약: SASE는 백홀 경로를 줄이고 클라우드 엣지에서 네트워크 품질과 보안 정책을 동시에 처리한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 전통 WAN+보안 | SASE | 선택 기준 |
|:---|:---|:---|:---|
| 회선 구조 | MPLS 중심 | 인터넷+SD-WAN+PoP | 지사 수와 해외 트래픽 비중 |
| 보안 위치 | 본사 보안 장비 | 분산 PoP | SaaS 직접 접속 비중 |
| 도입 방식 | 장비 증설 | 구독형 서비스 | OPEX, 라이선스, PoP 커버리지 |
| 데이터 통제 | 사내망 중심 DLP | SaaS API/Proxy DLP | 개인정보·영업비밀 업로드 통제 |

> 요약: SASE는 SaaS 사용량과 분산 근무 비중이 큰 조직에서 우선 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 공급자 종속 | 네트워크와 보안 기능 단일 서비스 의존 | 표준 로그, API, 단계적 전환 | 정책 이관 소요 시간 |
| PoP 지연 | 사용자 지역과 PoP 거리 증가 | 지역별 PoP 선택, 우회 경로 | p95 RTT, 터널 재연결 횟수 |
| 정책 충돌 | SWG, CASB, ZTNA 룰 중복 | 정책 우선순위 표준화 | 차단 오탐률, 룰 변경 건수 |
| TLS 검사 이슈 | 인증서 핀닝, 개인정보 통신 | 복호화 예외, 개인정보 분류 | 예외 도메인 수, DLP 탐지율 |

> 요약: SASE 리스크는 공급자 종속, PoP 품질, 정책 충돌, TLS 검사 예외에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 네트워크 품질 | p95 업무 앱 지연 150ms 이하 | synthetic monitoring, SD-WAN 지표 |
| 보안 탐지 | DLP 룰 적중과 악성 URL 차단 건수 | CASB/SWG 로그 |
| 접근 통제 | 앱별 ZTNA 정책 100% 매핑 | 정책 내보내기, CMDB 대조 |
| 운영 증적 | 로그 수집 성공률 99% 이상 | SIEM 수집률, 누락 이벤트 분석 |

> 요약: SASE는 품질, 탐지, 접근 통제, 로그 수집 지표가 동시에 관리될 때 운영 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 지사 회선을 인터넷+SD-WAN으로 전환하고, 업무별 SLA 기준에 따라 PoP 경로와 우회 경로를 정의함.
2. SWG, CASB, ZTNA 정책을 IdP 사용자 그룹과 연결하고, SaaS DLP와 사내 앱 접근 정책을 분리함.
3. SASE 로그를 SIEM/SOAR로 통합하고, URL 차단, SaaS 업로드, ZTNA 실패 이벤트를 사용자 ID 기준으로 상관분석함.

**결론 (2줄):**
- 기술사 판단: 분산 근무와 SaaS 비중이 높으면 SASE를 적용하고, 폐쇄망·저지연 전용망은 기존 WAN을 병행함.
- 향후 방향: SASE는 SSE와 SD-WAN을 API로 결합하고, AI 기반 정책 추천과 위협 대응 자동화로 확장됨.
