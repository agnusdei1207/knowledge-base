## Ⅰ. 개요
- **정의**: VLAN은 논리적 네트워크를 분할하며, STP는 브로드캐스트 스톰(루핑)을 차단하는 기술임.
- **배경 및 필요성**: 도메인 크기 증가로 인한 트래픽 과부하 및 다중 경로 구성 시 네트워크 순환(Loop) 방지.
- **출제 의도**: 논리적 분할(VLAN)과 이중화 구성 시 필수적인 브로드캐스트 스톰 방지(STP) 구조 이해

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **VLAN** | 하나의 물리적 스위치를 여러 논리적 네트워크로 분할하는 기술 | 하나의 사무실을 파티션으로 분리 |
| **Trunk Port** | 여러 VLAN 트래픽을 식별(VLAN ID 태깅)하여 단일 링크로 전송하는 포트 | 다양한 부서 우편물이 지나는 통합 배송로 |
| **STP** | 네트워크 루프를 감지하고 특정 포트를 논리적으로 차단(Block)하는 알고리즘 | 순환도로에서 한쪽 진입로 임시 통제 |

> 요약: VLAN은 트래픽 격리 및 분할을 제공하며, STP는 망 내 논리적 무결성을 보장함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **VLAN 할당 및 태깅**: 스위치 포트에 VLAN을 배정하고 트렁크 포트는 802.1Q 태그를 부착함.
2. **BPDU 교환**: 스위치 간 토폴로지 정보를 담은 BPDU 메시지를 교환함.
3. **루트 브리지 선출**: 가장 낮은 브리지 ID를 가진 스위치를 최상단(Root)으로 선출함.
4. **루프 차단 적용**: 경로 비용을 계산해 최적 경로 외 루프 발생 포트를 차단(Blocking)함.

> 요약: VLAN으로 트래픽을 분할한 뒤 BPDU를 교환해 최적 트리를 생성하고 중복 경로를 차단함.

## Ⅳ. 문제점
- STP의 느린 수렴 속도 (원인: 포트 상태 전이에 30~50초가 소요되어 장애 대응이 지연됨)
- 대역폭 낭비 (원인: STP가 한 경로를 막아 이중화된 링크 대역폭을 모두 활용할 수 없음)
- VLAN 간 라우팅 병목 (원인: 서로 다른 VLAN 통신 시 상위 L3 장비를 반드시 거쳐야 함)

## Ⅴ. 개선방안
- **단기 방안**: [단기] RSTP 적용 (링크 상태 변화 시 즉각 경로를 재계산해 수 초 내 수렴 달성)
- **중기 방안**: [중기] L3 스위치 기반 SVI 라우팅 (스위치 내부의 하드웨어 기반 라우팅으로 병목 해소)
- **장기 방안**: [장기] 다중 경로 라우팅 기반 패브릭 적용 (STP를 폐기하고 모든 링크를 활성화하는 차세대 L2 구조 전환)

## Ⅵ. 전망
- VLAN/STP 환경은 점차 VXLAN 및 SDN 기반의 유연한 오버레이(Overlay) 구조로 대체될 전망임.
