## 미리 알고가기

- 오케스트레이션은 여러 보안 도구를 연결해 한 흐름으로 움직이게 하는 방식임
- 플레이북은 반복 대응 절차를 순서대로 적어 둔 자동화 시나리오임
- 티켓 시스템은 분석가가 사건 처리 상태를 기록하는 업무 도구임
- 평균 대응 시간은 경보가 발생한 뒤 조치가 끝날 때까지 걸린 평균 시간임

## Ⅰ. 개요

- **정의/개념**: SOAR는 관제 시스템과 단말 탐지 도구와 방화벽과 티켓 시스템을 연결해 경보 분석과 증거 수집과 차단 조치를 표준 절차로 자동 실행하는 보안 대응 플랫폼임
- **배경/필요성**: 경보 수가 많아질수록 분석가는 반복 확인과 수작업 차단에 시간을 쓰게 되므로, 자주 반복되는 대응을 묶어 자동화할 체계가 필요함

## Ⅱ. 특징

- 여러 보안 도구를 한 흐름으로 묶어 대응 속도를 줄일 수 있음
- 플레이북으로 대응 절차를 표준화해 담당자 차이를 줄일 수 있음
- 사람이 승인해야 할 단계와 자동으로 끝낼 단계를 나눌 수 있음
- 오탐 경보를 자동 조치에 연결하면 정상 계정·주소·서비스까지 차단될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 대응 | SOAR |
|:---|:---|:---|
| 처리 방식 | 분석가가 도구를 오가며 직접 처리함 | 플레이북이 도구를 연결해 순서대로 처리함 |
| 속도 | 담당자 숙련도에 크게 좌우됨 | 반복 업무는 일정한 속도로 처리하기 쉬움 |
| 기록 관리 | 누락되거나 형식이 제각각일 수 있음 | 단계별 결과와 증적을 일관되게 남김 |
| 유의점 | 분석가별 판단 편차와 반복 작업이 발생함 | 오탐 경보가 자동 차단으로 이어지지 않도록 승인 조건이 필요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 경보 입력 | SIEM, EDR, 메일 보안 같은 경보 원천임 |
| 플레이북 엔진 | 대응 절차를 순서대로 실행함 |
| 연동 커넥터 | 방화벽과 계정 관리 시스템과 티켓 시스템을 연결함 |
| 케이스 관리 | 사건 상태와 증적을 기록함 |
| 분석가 | 승인과 예외 판단을 담당함 |

```text
+---------+    경보    +--------------+    자동 조치    +--------------+
| 경보 원천  | ------> | 플레이북 엔진   | -----------> | 보안 도구        |
+---------+          +--------------+               +--------------+
                              |
                              v
                         +-----------+
                         | 분석가·티켓 |
                         +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[경보 수신] -> [정보 보강] -> [조건 판단] -> [자동 조치] -> [사건 기록]
```

1. **경보 수신**: SIEM이나 다른 도구에서 경보를 받음
2. **정보 보강**: 자산 정보와 사용자 정보와 과거 이력을 붙임
3. **조건 판단**: 자동 차단인지 사람 승인인지 결정함
4. **자동 조치**: 계정 잠금이나 IP 차단이나 격리를 수행함
5. **사건 기록**: 결과를 케이스와 티켓에 남김

## Ⅵ. 실무 적용 및 유의점

1. 피싱 메일과 악성 URL 차단처럼 절차가 반복되는 업무는 플레이북으로 표준화하며, 오탐 경보가 정상 업무를 차단하지 않도록 자동 승인 범위를 제한하고 평균 대응 시간, 자동 조치 성공률, 오차 차단 건수를 확인함
2. 조직마다 절차가 다른 대응은 플레이북이 길어지기 쉬우므로 공통 단계부터 표준화하고 수동 개입 비율과 예외 처리 건수를 계속 봐야 함

## Ⅶ. 결론

SOAR의 핵심은 자동화 자체가 아니라 반복 대응을 표준 절차로 묶어 사람의 시간을 고위험 판단에 집중시키는 데 있음.
