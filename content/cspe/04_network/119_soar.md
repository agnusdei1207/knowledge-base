# 📖 【암기용】 개념 완전 이해

> 목적: SOAR를 보안 경보를 표준 절차로 처리하고 반복 대응을 자동화하는 운영 플랫폼으로 이해하게 만든다.

## 한눈에
- **개요**: SOAR는 SIEM, EDR, 방화벽, 티켓 시스템을 연결해 보안 이벤트 대응 절차를 playbook으로 자동 실행하는 플랫폼이다.
- **왜 필요한가**: 관제 경보가 많아지면 분석가가 IP 조회, 계정 잠금, 티켓 생성 같은 반복 작업에 시간을 사용한다.
- **핵심 직관**: 화재 신고가 들어오면 관제실, 소방서, 출입통제, 병원 연락을 정해진 순서로 자동 호출하는 비상 매뉴얼 시스템이다.

## 깊이 이해
- **배경·문제의식**: SIEM은 경보를 만들지만, 경보 확인, 증거 수집, 차단, 보고, 승인 절차는 별도 도구에 흩어져 있다.
- **작동 원리**: SOAR는 경보를 받아 위협 인텔리전스 조회, 자산 중요도 확인, 담당자 승인, EDR 격리, 방화벽 차단, 티켓 업데이트를 playbook으로 실행한다.
- **비유**: 병원 응급실에서 환자 상태에 따라 검사, 격리, 수술, 보호자 연락을 표준 절차표로 진행하는 것과 같다.
- **구체 예시**: 피싱 메일 경보가 들어오면 SOAR는 발신 도메인 평판 조회, 동일 메일 검색, 사용자 알림, 메일 격리, 티켓 종료 보고를 순차 실행한다.
- **흔한 오해·주의점**: SOAR는 모든 대응을 자동 차단하지 않는다. 고위험 조치는 승인 단계와 롤백 절차가 필요하다.

## 연결 개념
- SIEM - SOAR에 경보와 상관분석 결과 제공
- EDR/NDR - SOAR가 격리·차단 명령을 실행하는 대상
- Playbook - 탐지 유형별 대응 절차 자동화 단위

# 📝 【답안용】 시험 답안 템플릿

> 목적: SOAR 답안은 자동화 자체보다 경보 접수, 증거 수집, 승인, 대응, 보고의 절차 통제를 보여야 한다.
> 핵심: playbook, orchestration, case management, MTTR, audit trail을 연결한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SOAR는 보안 경보 처리 절차를 playbook으로 표준화하고 여러 보안 도구의 대응 동작을 오케스트레이션하는 플랫폼이다.
> 2. **가치**: 반복 조사와 차단 절차를 자동화해 MTTR을 줄이고, 분석가는 고위험 사건 판단에 집중한다.
> 3. **판단 포인트**: 자동화 대상 선정, 승인 단계, 도구 API 연동, 실패 롤백, 감사 기록이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대응 자동화 구조 이해 확인 | Playbook, Case, Connector, Approval | SOAR를 SIEM과 같은 탐지 도구로 설명 |
| 운영 절차 통제 확인 | 증거 수집, 차단, 격리, 보고, 롤백 | 자동 차단만 강조하고 승인 누락 |
| 지표 기반 효과 확인 | MTTR, 자동화율, playbook 성공률 | "운영 편의" 같은 표현 |

> 요약: SOAR 문제는 보안 경보를 표준 절차와 자동 실행으로 어떻게 대응하는지 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 보안 대응 자동화 플랫폼
- 배경: SIEM·EDR·메일·방화벽 경보가 증가하면 분석가의 반복 조사 시간이 늘어남.
- 필요성: playbook으로 증거 수집, 승인, 차단, 보고를 표준화해 MTTR을 단축해야 함.
- 판단 기준: 반복 경보 비율, API 연동 가능성, 오탐 위험, 승인 필요 조치를 기준으로 도입함.

---

## Ⅱ. 구조 및 구성요소

```text
SIEM/EDR/Email Alert -> SOAR Case -> Playbook Engine
                     -> TI/Asset Lookup -> Approval
                     -> EDR/Firewall/IdP Action -> Report/Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Case Management | 경보를 사건 단위로 묶고 담당자를 지정 | 중복 경보 병합, SLA 관리 |
| Playbook Engine | 대응 절차를 조건·분기·승인 단계로 실행 | 실패 분기와 롤백 필요 |
| Connector/API | SIEM, EDR, IdP, Firewall, Email과 연동 | API 권한 최소화와 토큰 관리 |
| Threat Intel | IP, 도메인, 해시 평판을 조회 | 오탐 방지를 위한 다중 소스 확인 |
| Audit Trail | 실행 결과와 승인 이력을 저장 | 감사, 사후 분석, 책임 추적 |

> 요약: SOAR는 사건 관리, playbook, API 연동, 위협 정보, 감사 기록으로 대응 절차를 자동화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
경보 접수 -> 사건 생성 -> 중복/우선순위 판단 -> 증거 수집
-> 승인 여부 판단 -> 자동 조치 -> 결과 검증 -> 보고/종결
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | SIEM·EDR·메일 경보를 Case로 생성 | 중복 병합, 자산 중요도, 심각도 |
| 2 | TI, CMDB, 로그 검색으로 증거를 수집 | IP 평판, 사용자 이력, 파일 해시 |
| 3 | playbook 조건에 따라 승인 또는 자동 실행 결정 | 고위험 조치 승인자 지정 |
| 4 | EDR 격리, 계정 잠금, 방화벽 차단을 실행 | API 응답, 조치 성공 여부 |
| 5 | 처리 결과를 보고서와 티켓으로 저장 | MTTR, playbook 성공률, 감사 로그 |

> 요약: SOAR는 경보를 사건으로 바꾸고 증거 수집부터 조치와 보고까지 표준 절차로 실행한다.

## Ⅳ. 특징

| 구분 | 수동 대응 | SOAR 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 조사 | 분석가가 도구별 조회 | TI, CMDB, SIEM 자동 조회 | API connector, enrichment |
| 조치 | 콘솔별 수동 차단 | playbook 기반 격리·차단 | EDR isolate, IdP lock |
| 품질 | 담당자별 절차 편차 | 표준 절차와 승인 이력 | audit trail, SLA |
| 한계 | 자동화 범위 낮음 | 오탐 자동 차단 위험 | approval, rollback |

> 요약: SOAR는 반복 대응 절차를 표준화하지만, 고위험 조치에는 승인과 롤백 절차가 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SIEM 중심 대응 | SOAR 연계 대응 | 선택 기준 |
|:---|:---|:---|:---|
| 역할 | 탐지·경보 생성 | 조사·조치·보고 자동화 | 반복 작업 비율 |
| 데이터 | 로그와 correlation | 경보, 자산, TI, 티켓 | API 연동 범위 |
| 운영 지표 | MTTD, 오탐률 | MTTR, 자동화율, 성공률 | 대응 병목 위치 |
| 통제 | 관제원 수동 조치 | 승인 단계와 playbook | 오탐 차단 위험 |

> 요약: SIEM 경보 처리량이 병목이면 SOAR를 연계해 조사와 조치 시간을 줄인다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 자동 차단 | 경보 품질 낮음 | 승인 단계, 위험 점수 임계치 | 오조치 건수 |
| API 권한 남용 | SOAR 토큰이 과도한 권한 보유 | 최소 권한, 토큰 회전 | 권한 감사 결과 |
| playbook 실패 | 도구 API 변경, 네트워크 오류 | 재시도, 실패 분기, 수동 전환 | playbook 성공률 |
| 절차 고착 | 위협 변화 반영 지연 | 월간 playbook 리뷰 | 룰 변경 주기 |

> 요약: SOAR 리스크는 오탐 조치, API 권한, 실행 실패, 절차 갱신 지연으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 대응 시간 | MTTR 30% 이상 단축 | 도입 전후 티켓 시간 비교 |
| 자동화율 | 반복 경보 50% 이상 playbook 처리 | Case 통계 |
| 실행 품질 | playbook 성공률 95% 이상 | 실행 로그, 실패 원인 분석 |
| 감사 증적 | 승인자·조치·결과 100% 기록 | audit trail 샘플링 |

> 요약: SOAR 성과는 MTTR, 자동화율, playbook 성공률, 감사 기록 완전성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 피싱, 악성 해시, 계정 탈취, WAF 반복 공격처럼 빈도와 절차가 명확한 사건부터 playbook을 작성함.
2. SOAR Connector에 EDR 격리, IdP 계정 잠금, 방화벽 차단 API를 연결하고 고위험 조치에는 승인 단계를 둠.
3. MTTR, 자동화율, playbook 성공률, 오조치 건수를 월간 지표로 관리하고 실패 분기를 보완함.

**결론 (2줄):**
- 기술사 판단: SOAR는 SIEM 경보가 많고 반복 대응 절차가 표준화된 조직에서 우선 적용함.
- 향후 방향: SOAR는 SIEM, XDR, ITSM, 생성형 AI 분석 보조와 결합해 대응 자동화 범위를 확대함.
