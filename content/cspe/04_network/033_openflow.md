## Ⅰ. 개요
- **정의**: SDN 아키텍처에서 제어 평면(컨트롤러)과 데이터 평면(스위치) 간 통신을 위한 표준 개방형 사우스바운드(Southbound) API 프로토콜임.
- **배경/필요성**: 스위치의 제어 로직을 외부에 분리하여 벤더에 종속되지 않는 프로그래밍 가능한 네트워크 실현 목적.
- **출제 의도**: OpenFlow의 동작 원리(Flow Table), 구성요소, 기존 L2/L3 스위치 처리 방식과의 차이점 이해.

## Ⅱ. 구성요소
```text
+-----------------------+
|    SDN Controller     |
+-----------+-----------+
            | OpenFlow Protocol (TLS/TCP)
+-----------+-----------+
|    Secure Channel     |
+-----------+-----------+
|    OpenFlow Switch    |
| +-------------------+ |
| |    Flow Table     | |
| +-------------------+ |
+-----------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| SDN Controller | 네트워크 장비들을 중앙에서 제어하고 Flow Rule을 내려보내는 두뇌 | 지휘관 |
| Flow Table | 스위치 내부에 저장되는 패킷 매칭 규칙 및 액션(Action) 목록 | 행동 지침서 |
| Secure Channel | 컨트롤러와 스위치 간 명령과 상태 정보를 안전하게 교환하는 통신로 | 암호화된 통신망 |
> 요약: 컨트롤러가 Secure Channel을 통해 스위치의 Flow Table을 갱신하여 패킷의 경로를 제어함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 패킷 인입 |-> | Flow 매칭   |-> | 컨트롤러질의|-> | Rule 캐싱 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **패킷 인입**: 스위치의 특정 포트로 외부 데이터 패킷이 처음 들어옴.
2. **Flow 매칭**: 인입된 패킷의 헤더 정보를 기반으로 내부 Flow Table의 매치 필드와 비교함(Match/Action).
3. **컨트롤러 질의**: 일치하는 Rule이 없으면(Table Miss), 패킷의 일부를 컨트롤러로 전송(Packet-In)하여 처리 방법을 요청함.
4. **Rule 캐싱**: 컨트롤러가 계산된 포워딩 규칙(Packet-Out, Flow-Mod)을 내려주면 이를 Flow Table에 저장(캐싱)하고 패킷을 전송함.
> 요약: 스위치는 수신한 패킷을 Flow Table과 대조하고, 미지의 패킷은 컨트롤러에 질의하여 규칙을 학습함.

## Ⅳ. 문제점
- **지연 시간(Latency) 증가**: Table Miss 발생 시 매번 컨트롤러에 질의해야 하므로 초기 통신 지연 발생.
- **컨트롤러 병목 현상**: 대량의 새로운 플로우 발생(예: DDoS 공격) 시 컨트롤러의 처리 한계 도달 및 스위치 메모리(TCAM) 고갈.
- **보안 설정 복잡도**: 컨트롤러와 스위치 간 TLS 암호화 채널 구성 및 인증서 관리의 운영상 번거로움.

## Ⅴ. 개선방안
- **선제적 규칙 적용**: 질의 없이 처리 가능하도록 사전에 컨트롤러가 규칙을 내려보내는 Proactive 방식 병행 (단기).
- **데이터 평면 최적화**: 룰 오프로딩 기능을 적용하여 컨트롤러 부하 분산 및 스위치 TCAM 최적화 (중기).
- **차세대 프로토콜 진화**: OpenFlow의 고정된 헤더 파싱 한계를 극복하기 위해 P4 기반의 데이터 평면 프로그래밍 기술 도입 (장기).

## Ⅵ. 전망
- OpenFlow는 SDN의 초석을 다진 프로토콜이나, 최근에는 단순 제어를 넘어 데이터 평면을 완전 프로그래밍 가능한 P4 기술로 진화 중임.
- 데이터 센터 및 통신사 인프라에서는 여전히 Whitebox 스위치 및 가상 스위치(OVS)를 통해 광범위하게 활용될 것임.
