# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: TCP/IP 4계층 모델은 현재 인터넷을 실제로 구동하는 **사실상 표준(De facto)** 프로토콜 스택으로, OSI 7계층(001 참조)을 실용적 4계층으로 압축한 구조다.
- **왜 필요한가**: OSI는 이론적으로 정교하나 구현이 무겁고 느렸다. ARPANET에는 "노드가 일부 파괴돼도 살아남는" 견고하고 빠른 통신이 먼저 필요했다.
- **핵심 직관**: 이론보다 실전. 프로그램(응용)이 데이터를 만들면 → 빠짐없이 전달하고(TCP) → 목적지를 찾아가며(IP) → 랜선으로 쏜다(네트워크 접속). 핵심은 **TCP와 IP의 역할 분담**이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

계층화·캡슐화·PDU(세그먼트/패킷/프레임)·MAC/IP/포트 개념은 001에서 다뤘으므로, 여기서는 TCP/IP 고유 용어를 중심으로 정리한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 프로토콜 스택 (Protocol Stack) | 계층별 프로토콜을 쌓아 실제로 구현한 통신 소프트웨어 묶음 | 참조 모델이 도면이면, 스택은 그 도면대로 지은 실제 건물 |
| TCP (전송 제어 프로토콜) | 연결을 맺고 순서·재전송으로 신뢰성을 보장하는 연결 지향 프로토콜 (L4) | 등기우편: 받았는지 확인하고 분실 시 다시 보냄 |
| UDP (사용자 데이터그램 프로토콜) | 연결 없이 빠르게 쏘는 비신뢰 전송 프로토콜 (L4) | 일반우편: 빠르지만 도착 보증 없음 |
| IP (인터넷 프로토콜) | 목적지까지 패킷 경로를 정하는 비연결형·최선노력(Best-effort) 프로토콜 (L3) | 택배 허브: 배달만 시도, 도착 책임은 안 짐 |
| Best-effort (최선 노력) | 전달을 "시도"만 하고 성공을 보장하지 않는 방식 | 최선을 다하되 결과는 약속 안 함 |
| ARP (주소 결정 프로토콜) | IP 주소로 상대 MAC 주소를 알아내는 프로토콜 (네트워크 접속) | 집 주소로 그 집 우편함 번호를 알아내는 것 |
| 네트워크 접속 계층 | OSI의 L2 데이터링크 + L1 물리를 합친 최하위 계층 | 우체국의 집배+트럭을 한 부서로 묶은 것 |
| De facto 표준 | 공식 인증이 아니라 시장이 널리 채택해 사실상 표준이 된 것 | 규정에 없어도 다들 쓰는 관행 (OSI=De jure와 대비) |
| RFC | IETF가 인터넷 프로토콜 규격을 공개 문서로 정의한 표준 시리즈 | 프로토콜의 공식 사용설명서 |
| QUIC / HTTP/3 | UDP 위에 신뢰성·암호화·멀티플렉싱을 얹은 차세대 전송 프로토콜 | TCP의 느린 핸드셰이크·HoL 병목을 우회한 신형 등기 |

## 깊이 이해
- **배경·문제의식**: 1970년대 미 국방부(DoD)는 핵 공격으로 일부 노드가 파괴돼도 우회 경로로 살아남는 네트워크가 필요했다. 그래서 완결적 이론(OSI)보다 "지금 돌아가는 실용 스택"을 먼저 만들었고, 그 결과가 TCP/IP다. OSI 표준이 완성(1984)되기 전에 이미 인터넷이 TCP/IP로 돌아가 시장을 선점했다.
- **작동 원리(어떻게+왜)**: 캡슐화·역캡슐화 메커니즘 자체는 OSI와 동일하다(001 참조). 차이는 **계층 통합**이다. OSI 상위 3계층(응용·표현·세션)을 하나의 응용 계층으로, 하위 2계층(데이터링크·물리)을 네트워크 접속 계층으로 합쳤다. 통합이 가능한 이유는 표현·세션 기능을 별도 계층으로 강제하지 않고, 필요한 응용이 알아서 처리(예: TLS 암호화)하도록 위임했기 때문이다. 이 "얇은 허리(Thin Waist)" 구조 — 중앙에 IP 하나만 두고 위아래로 다양한 프로토콜을 꽂는 방식 — 이 확장성의 핵심이다.
- **TCP와 IP의 역할 분담(핵심)**: IP는 "경로 찾아 배달 시도"만 하는 비신뢰 계층이고, TCP는 그 위에서 "빠진 것 다시 보내고 순서 맞추는" 신뢰성을 책임진다. 신뢰성을 네트워크(L3)가 아니라 종단(L4)이 지는 이 원칙을 **End-to-End 원칙**이라 하며, 중간 라우터를 단순하게 유지해 확장성을 얻는다.
- **비유**: 편지 내용 작성과 봉투 밀봉(응용)을 한 번에 끝내고, 등기(TCP)/일반(UDP) 우편을 고른 뒤, 주소를 적어(IP) 배달을 맡기고, 트럭·집배(네트워크 접속)로 실어 나른다. 우체국(IP)은 배달만 시도하고, 도착 확인·재발송은 등기 서비스(TCP)가 챙긴다.
- **구체 예시**: 브라우저(응용)가 TCP 443 포트로 3-way handshake(전송)를 맺고, 목적지 IP로 패킷(인터넷)을 만들고, ARP로 알아낸 게이트웨이 MAC을 붙여 이더넷 프레임(네트워크 접속)으로 내보낸다. IPv4 주소는 32비트, 헤더 기본 20바이트다.
- **흔한 오해·주의점**: OSI가 "국제 공식표준(De jure)"이라 더 우월해 보이지만, 실제 전 세계 인터넷 소프트웨어는 TCP/IP "사실상 표준(De facto)"으로 돌아간다. 또 TCP/IP를 5계층(물리·데이터링크·인터넷·전송·응용)으로 그리는 교재도 있는데, 이는 네트워크 접속을 물리·데이터링크로 다시 나눈 변형이다.

## 연결 개념
- OSI 7계층(001) — TCP/IP 이해·설계를 돕는 참조 모델
- TCP 3-way handshake(026) — TCP 연결 수립 절차
- QUIC·HTTP/3(032) — TCP의 구조적 한계(HoL)를 극복하는 진화 방향

> 1. **본질**: TCP/IP 4계층은 인터넷을 실제 구동하는 DoD 유래의 실용적 De facto 통신 스택임.
> 2. **가치**: OSI 상위 3계층을 응용으로 통합해 구현 복잡도를 낮추고, 얇은 허리(IP) 구조로 확장성을 확보함.
> 3. **판단 포인트**: TCP/IP 원리 재설명보다, OSI 대비 계층 통합 효과와 QUIC·TLS로의 스택 진화를 짚어야 함.

## Ⅰ. 개요 및 필요성

- 개요: 인터넷 통신을 실제 구동하는 4계층 구성의 De facto 프로토콜 스택임
- 배경: (001 OSI 참조) OSI의 구현 복잡성 대신, ARPANET에 필요한 견고·실용 프로토콜 요구
- 필요성: 구현 복잡도를 낮추고 이기종 네트워크 간 매끄러운 패킷 라우팅을 보장하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
TCP/IP 4계층                         <- OSI 7계층 매핑
응용 (Application)                    <- L7 응용 + L6 표현 + L5 세션
전송 (Transport)                     <- L4 전송
인터넷 (Internet)                    <- L3 네트워크
네트워크 접속 (Network Access)        <- L2 데이터링크 + L1 물리
```

| 계층 | 역할 | 주요 프로토콜 | 식별자 |
|:---|:---|:---|:---|
| 응용 (Application) | 응용 프로그램 간 데이터 송수신 | HTTP, DNS, FTP, SMTP | URL, 이메일 주소 |
| 전송 (Transport) | 종단 간 신뢰성·흐름·오류 제어 | TCP, UDP | 포트 번호 |
| 인터넷 (Internet) | 최적 경로 라우팅·패킷 포워딩 | IP, ICMP, ARP | IP 주소 |
| 네트워크 접속 | 매체 접속·인접 노드 프레이밍 | Ethernet, Wi-Fi | MAC 주소 |

> 요약: OSI 상위 3계층을 응용으로, 하위 2계층을 네트워크 접속으로 통합해 구현 효율을 높임.

---

## Ⅲ. 동작원리 및 흐름도

```text
HTTP 요청(Data) → TCP 헤더·포트 부착(Segment) → IP 헤더·주소 부착(Packet)
  → Ethernet 헤더·MAC 부착(Frame) → 매체 전송
```

1. **응용 데이터 생성**: HTTP 등 규격에 맞춰 데이터를 인코딩하고 필요 시 TLS로 암호화함
2. **세그먼트화 (TCP)**: 송수신 포트와 순서번호를 부착하고 3-way handshake로 연결을 수립함
3. **패킷화 (IP)**: 출발지·목적지 IP를 부착하고 라우팅 테이블로 다음 홉을 결정함
4. **프레임화 (Ethernet)**: ARP로 알아낸 다음 홉 MAC을 부착해 프레임을 만들고 랜카드로 송출함

> 요약: 상위→하위로 캡슐화가 진행되며, 각 헤더에 전송·라우팅·매체 접속용 제어정보가 담김.

---

## Ⅳ. 특징

- De facto 표준: 산업계 채택이 먼저 이뤄져 사실상 표준이 됨 (규격은 IETF RFC로 구체화)
- 얇은 허리(Thin Waist): 중앙에 IP 하나만 두고 위아래에 다양한 프로토콜을 꽂아 확장성 확보
- End-to-End 원칙: 신뢰성은 종단 TCP가 지고 중간 라우터는 단순 유지해 확장성·생존성 확보
- 계층별 유연 보안: 보안이 한 계층에 종속되지 않음 (IPsec은 L3, TLS는 L4 위에 적용)
- 동적 우회: 라우터 장애 시 IP가 대체 경로를 동적으로 탐색해 생존성 확보

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | OSI 7계층 | TCP/IP 4계층 |
|:---|:---|:---|
| 표준 성격 | 국제 공식표준(De jure) | 사실상 표준(De facto) |
| 제정 주체 | ISO | IETF / 미 국방부(DoD) |
| 계층 분리 | 엄격한 7단계 분리 | 실용적 4단계 통합 |
| 신뢰성 제어 | L3에서 연결형(X.25)도 정의 | 신뢰성=L4(TCP), 라우팅=L3(IP) 분리 |
| 용도 | 개념 설계·교육·분석 | 실제 인터넷 구동 |

> 요약: 장비 벤더는 OSI로 개념을 설계하나, OS 네트워크 스택은 TCP/IP 구조를 직접 구현함.

- TCP HoL 블로킹: 단일 TCP 연결에서 패킷 손실 시 후속 대기 → UDP 기반 QUIC(HTTP/3) 도입
- 평문 전송 취약: 기본 TCP/IP는 암호화 미포함 → IPsec(L3)·TLS(L4 위)로 암호화 적용
- IPv4 주소 고갈: 32비트 주소 한계 → IPv6 전환, NAT로 사설 주소 다중화

---

## Ⅵ. 실무 적용 및 결론

- 차세대 전송 적용: TCP 세션과 TLS 핸드셰이크를 통합한 UDP 기반 QUIC(HTTP/3)로 체감 지연 단축함
- End-to-End 암호화: 모든 응용 트래픽에 mTLS를 강제하고 Zero Trust 기반으로 서비스 간 통신을 인증함
- 커널 스택 관측: eBPF로 TCP/IP 스택 지표(재전송·RTT)를 오버헤드 없이 수집해 컨테이너 가시성 확보함
- 결론(조건부 판단): 견고·실용 설계로 인터넷의 기반이 됐으나, 모바일·5G에서는 TCP HoL 극복이 필수임
- 결론(향후 방향): 커널 스택을 우회하는 DPDK·SmartNIC로 유저 스페이스 패킷 처리량을 극대화하는 추세임
