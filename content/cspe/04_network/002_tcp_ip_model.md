## 미리 알고가기

- End-to-End 원칙: 복잡한 제어를 네트워크 내부보다 종단 호스트가 맡는 설계 원칙임
- Best Effort: IP 계층이 전달을 시도하지만 도착, 순서, 재전송을 직접 책임지지 않는 방식임
- 포트 번호: 하나의 호스트 안에서 통신 대상 프로세스를 구분하는 전송 계층 식별자임
- Thin Waist: 다양한 응용과 매체 사이를 공통 IP 계층이 연결하는 구조를 말함

## Ⅰ. 개요

- **정의/개념**: TCP/IP 4계층 모델은 응용, 전송, 인터넷, 네트워크 접근 계층으로 인터넷 프로토콜 묶음을 설명하는 통신 구조임
- **배경/필요성**: 다양한 응용 서비스와 물리 매체가 같은 인터넷에서 통신하려면 IP를 중심으로 계층별 역할과 주소 체계를 나누는 구조가 필요함

## Ⅱ. 특징

- 응용은 서비스 규칙, 전송은 프로세스 간 전달, 인터넷은 경로 선택, 접근 계층은 링크 전달을 맡음
- IP 계층은 상태를 최소화해 라우터가 패킷별 목적지 주소를 보고 전달하도록 함
- 신뢰성, 순서, 혼잡 제어는 주로 TCP 같은 종단 프로토콜에서 처리함
- UDP 기반 QUIC처럼 일부 최신 프로토콜은 응용과 전송 경계를 다시 설계함

## Ⅲ. 종류 및 비교

| 판단 기준 | OSI 7계층 | TCP/IP 4계층 |
|:---|:---|:---|
| 모델 성격 | 기능을 세분화한 참조 모델임 | 인터넷 프로토콜 구현을 설명하는 모델임 |
| 계층 수 | 7계층으로 세션과 표현을 별도 구분함 | 4계층으로 응용에서 세션과 표현 처리를 함께 다룸 |
| 주소 체계 | 계층별 주소와 PDU를 교육적으로 구분함 | MAC, IP, Port를 실제 통신 기준으로 설명함 |
| 적용 초점 | 장애 위치와 기능 책임을 설명할 때 유리함 | 실제 인터넷 구성과 프로토콜 배치를 설명할 때 유리함 |

> 요약: TCP/IP는 실제 인터넷 통신을 설명하는 구현 중심 모델이며 OSI는 세부 책임을 나누는 참조 기준임

## Ⅳ. 구성요소 및 구조

| 계층 | 설명 |
|:---|:---|
| 응용 계층 | HTTP, DNS, SMTP처럼 사용자가 요구한 서비스의 메시지 형식을 정의함 |
| 전송 계층 | TCP, UDP처럼 포트 기반으로 프로세스 간 데이터 전달 방식을 정함 |
| 인터넷 계층 | IP, ICMP처럼 목적지 주소와 라우팅 기준으로 패킷을 전달함 |
| 네트워크 접근 계층 | Ethernet, Wi-Fi처럼 같은 링크 안에서 프레임과 물리 전송을 처리함 |

```text
+-------------+     HTTP, DNS
| Application |
+-------------+     TCP, UDP
| Transport   |
+-------------+     IP, ICMP
| Internet    |
+-------------+     Ethernet, Wi-Fi
| Net Access  |
+-------------+
```

> 요약: TCP/IP 구조는 서비스 메시지, 종단 전달, IP 경로 선택, 링크 전송을 나눠 인터넷 통신을 완성함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 서비스요청 | --> | 세그먼트화 | --> | IP전달   | --> | 링크전송 |
+----------+     +----------+     +----------+     +----------+
```

1. **서비스요청**: 응용 계층이 서비스별 메시지를 생성함
2. **세그먼트화**: 전송 계층이 포트와 전송 방식을 붙여 세그먼트나 데이터그램을 만듦
3. **IP전달**: 인터넷 계층이 목적지 IP와 라우팅 테이블을 기준으로 다음 홉을 정함
4. **링크전송**: 접근 계층이 MAC 주소와 프레임을 사용해 인접 장비로 보냄

## Ⅵ. 실무 적용 및 유의점

1. 장애 분석에서는 DNS, 포트 연결, IP 경로, 링크 상태를 계층별로 분리해 확인해야 하며 질의 로그, 세션 상태, 라우팅 테이블, 인터페이스 오류로 원인을 좁힘
2. QUIC이나 VPN처럼 계층을 겹쳐 쓰는 기술은 단순 4계층 매핑만으로 병목을 찾기 어려우므로 캡슐화 위치와 암호화 구간을 함께 확인함

## Ⅶ. 결론

TCP/IP 4계층 모델은 인터넷 구현을 계층별 책임과 식별자로 설명하게 해 주는 실무 기준임.

## 작성 근거(검토용)

- TCP/IP의 판단 기준은 "실제 인터넷 구현"이므로 계층별 프로토콜, 주소, 처리 책임을 중심으로 재구성함
- 막연한 성능 표현은 QUIC, 캡슐화, 암호화 구간처럼 확인 가능한 요소로 치환함
- 결론은 미래 예측이 아니라 구현 모델로서의 설명 역할을 회수함
