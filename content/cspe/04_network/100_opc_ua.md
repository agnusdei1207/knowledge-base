## 미리 알고가기

- PLC는 설비 제어를 담당하는 산업용 제어기임
- 정보 모델은 데이터 값뿐 아니라 그 의미와 관계까지 함께 표현하는 구조임
- 주소 공간은 OPC UA 서버가 외부에 공개하는 데이터와 객체의 계층 구조임
- 구독은 값이 바뀔 때마다 계속 받아보는 방식이고 읽기는 요청 시점의 값을 가져오는 방식임

## Ⅰ. 개요

- **정의/개념**: OPC UA는 산업 장비와 시스템이 데이터를 같은 의미 체계와 보안 절차로 주고받을 수 있게 만든 산업 통신 표준임
- **배경/필요성**: 제조사마다 다른 프로토콜과 데이터 형식을 그대로 두면 PLC와 SCADA와 MES와 클라우드를 연결할 때마다 변환 비용과 해석 오류가 반복되므로 공통 모델이 필요함

## Ⅱ. 특징

- 값만 보내는 것이 아니라 데이터 의미와 구조를 함께 표현함
- 읽기와 쓰기와 구독을 표준 방식으로 지원해 상위 시스템 연동이 쉬움
- 인증과 암호화와 세션 관리가 표준 안에 포함돼 있음
- 정보 모델 설계를 느슨하게 하면 같은 OPC UA라도 상호운용성이 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Modbus/TCP | OPC UA |
|:---|:---|:---|
| 데이터 표현 | 레지스터 값 중심으로 단순함 | 객체와 속성과 관계까지 표현 가능함 |
| 보안 기능 | 별도 보안 장치에 의존하는 경우가 많음 | 표준 안에 인증과 암호화 절차가 포함됨 |
| 상호운용성 | 제조사별 해석 차이가 남기 쉬움 | 공통 정보 모델을 맞추면 해석 일관성이 높아짐 |
| 적합한 환경 | 단순 값 읽기와 제어 | 복합 설비 데이터 통합과 상위 시스템 연계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| OPC UA 서버 | 장비 데이터와 기능을 주소 공간 형태로 외부에 공개함 |
| OPC UA 클라이언트 | 필요한 노드를 찾아 읽거나 쓰거나 구독함 |
| 정보 모델 | 변수와 객체와 이벤트의 의미를 정해 상호운용 기반을 만듦 |
| 보안 계층 | 인증서와 세션과 암호화를 관리함 |
| 게이트웨이 | 기존 설비 프로토콜을 OPC UA로 변환해 상위 연동을 돕는 장치임 |

```text
+-----------+    +-----------+    +-----------+    +-----------+
| 설비 데이터    | -> | OPC UA 서버 | -> | 정보 모델      | -> | 클라이언트·응용 |
+-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 모델 정의      | -> | 서버 공개      | -> | 클라이언트 접속 | -> | 읽기·구독 수행  | -> | 보안 검증      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **모델 정의**: 장비 데이터와 이벤트와 관계를 정보 모델로 정함
2. **서버 공개**: OPC UA 서버가 주소 공간으로 데이터를 노출함
3. **클라이언트 접속**: 상위 시스템이 인증 절차를 거쳐 세션을 맺음
4. **읽기와 구독 수행**: 필요한 값을 읽거나 변경 통지를 계속 받음
5. **보안 검증**: 인증서와 권한과 암호화 상태를 확인하며 운영함

## Ⅵ. 실무 적용 및 유의점

1. 스마트공장 통합에서는 OPC UA가 설비 간 의미 차이를 줄이는 데 유리하지만 정보 모델을 제각각 만들면 효과가 떨어지므로 공통 네이밍과 노드 설계를 먼저 맞추고 연동 성공률과 데이터 해석 오류를 확인해야 함
2. 인증서를 오래 방치하면 만료나 신뢰 체인 문제로 연결이 끊길 수 있으므로 갱신 절차를 운영에 포함하고 세션 실패율과 인증 오류 건수를 계속 확인해야 함

## Ⅶ. 결론

OPC UA의 가치는 통신 자체보다 데이터 의미와 보안을 함께 표준화해 산업 시스템 간 해석 차이를 줄이는 데 있음
