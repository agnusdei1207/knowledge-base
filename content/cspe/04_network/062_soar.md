## Ⅰ. 개요
- **정의**: 보안 오케스트레이션·자동화·대응을 통합하여 인시던트 처리를 자동화하는 플랫폼
- **배경/필요성**: SIEM(061)이 탐지한 경보를 수동 처리하면 MTTR이 길어지므로 자동화가 필요함
- **비유**: 119 신고 접수 후 소방차·구급차를 자동 배차하는 지령 시스템

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 운영 자동화 체계 이해 | Playbook 기반 오케스트레이션 | SIEM(061)은 탐지, SOAR는 대응 자동화로 구분 |

> 요약: SIEM 경보를 Playbook으로 자동 분류·분석·대응하여 보안 운영을 효율화하는 플랫폼임

## Ⅱ. 구성요소
```text
[SIEM Alert] ---> [Ingestion] ---> [Playbook Engine]
                                        |
                                   +----+----+
                                   |         |
                                   v         v
                             [Enrichment] [Action]
                                   |         |
                                   +----+----+
                                        v
                                  [Case Mgmt]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Playbook Engine | 조건·분기 기반 자동화 워크플로 실행 | 응급실 프로토콜 매뉴얼 |
| Enrichment | TI·CMDB 조회로 경보에 컨텍스트 부여 | 환자 과거 병력 조회 |
| Action Module | 차단·격리·티켓 생성 등 자동 대응 수행 | 처방전에 따른 투약 |
| Case Management | 인시던트 이력 추적·보고서 생성 | 진료 기록부 관리 |

> 요약: Playbook 중심으로 경보 수집-보강-대응-이력관리를 자동 수행함

## Ⅲ. 절차
```text
Step1 --> Step2 --> Step3 --> Step4
경보수집   컨텍스트   자동대응   사후관리
           보강
```
- 1단계: SIEM·EDR 등에서 경보를 수집하고 중복 제거·우선순위 분류함
- 2단계: TI 피드·CMDB·Whois 조회로 IOC 컨텍스트를 자동 보강함
- 3단계: Playbook 조건에 따라 IP 차단·계정 잠금·샌드박스 분석 수행함
- 4단계: 케이스 생성·타임라인 기록·사후 보고서를 자동 생성함

> 요약: 수집-보강-대응-관리의 4단계를 Playbook으로 자동 실행함

## Ⅳ. 문제점
- Playbook 관리 부담: 위협 유형별 Playbook 작성·갱신 — 보안 인력의 지속적 유지보수 필요
- 오탐 자동 대응 위험: 오탐 경보에 차단 액션 실행 — 정상 서비스 중단 가능성 존재
- 통합 복잡성: 이기종 보안 도구 API 연동 — 커넥터 호환성 유지 비용 증가

> 요약: Playbook 유지보수·오탐 대응 위험·이기종 연동 복잡성이 과제임

## Ⅴ. 개선방안
1. 단기: Playbook 템플릿 마켓플레이스 활용으로 작성·갱신 부담 경감
2. 중기: 신뢰도 스코어링 기반 단계적 대응으로 오탐 시 자동 차단 방지
3. 장기: 표준 API(OpenC2) 기반 연동으로 커넥터 호환성 문제 해소

> 요약: 템플릿 활용·단계적 대응·표준 API 도입으로 성숙도를 높일 필요

## Ⅵ. 전망
- 발전 방향: AI 기반 자율 대응(Autonomous SOC)으로 Playbook 자동 생성·실행 확대
- 기술사적 판단: SIEM-SOAR-XDR 통합 플랫폼이 SOC 표준 아키텍처로 정착 추세임
- 기술사 제언: 단계적 자동화 수준(L1→L3)을 정의하고 조직 성숙도에 맞게 도입할 필요
