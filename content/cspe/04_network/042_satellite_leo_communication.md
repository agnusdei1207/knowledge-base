## Ⅰ. 개요
- **정의**: 고도 200~2,000km 저궤도 위성 군집을 활용하여 광역 통신 서비스를 제공하는 기술임
- **배경/필요성**: 지상 인프라가 부재한 해양·오지·재난 지역에서 통신 연결이 필요함
- **비유**: 하늘에 떠 있는 수천 개의 중계 드론이 릴레이로 신호를 전달하는 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GEO·MEO·LEO 궤도별 특성 비교 | LEO의 저지연(20~40ms) 장점 | 위성 간 핸드오버 빈번 문제 언급 필요 |

> 요약: 저궤도 위성 군집으로 저지연·광역 통신을 실현하는 기술임

## Ⅱ. 구성요소
```text
User Terminal <--RF--> LEO Satellite <--ISL--> LEO Satellite <--RF--> Ground Station
                           |                                            |
                      Onboard Processing                          Core Network
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| LEO Satellite | 저궤도에서 지상 신호를 중계하는 위성체 | 하늘의 무선 기지국 |
| ISL (Inter-Satellite Link) | 위성 간 레이저·RF 링크로 데이터를 릴레이하는 경로 | 위성끼리 잇는 다리 |
| Ground Station | 위성 신호를 지상 코어 네트워크에 연결하는 관문국 | 항구의 하역장 |
| User Terminal | 사용자가 위성과 직접 통신하는 단말 장치 | 위성 전화기 |

> 요약: 사용자 단말-위성-ISL-관문국으로 이어지는 우주-지상 통합 구조임

## Ⅲ. 절차
```text
Terminal -> Uplink -> Satellite -> ISL Relay -> Satellite -> Downlink -> Ground Station
Ground Station -> Core Network -> Internet/PSTN
```
- 1단계: 사용자 단말이 Ku/Ka 대역으로 가시권 위성에 Uplink 신호 전송
- 2단계: 위성이 ISL을 통해 목적지 근처 위성까지 데이터를 릴레이함
- 3단계: 목적지 위성이 관문국으로 Downlink하여 지상 코어망에 연결함
- 4단계: 위성 이동에 따라 핸드오버를 수행하여 통신 연속성을 유지함

> 요약: Uplink-ISL릴레이-Downlink-핸드오버의 4단계로 통신을 수행함

## Ⅳ. 문제점
- 빈번한 핸드오버: 위성 이동 속도(약 7.8km/s)로 수 분마다 위성 교체가 발생하여 세션 유지 곤란
- 대량 위성 관리: 수천 기 군집의 궤도 유지·충돌 회피·수명 관리 비용 증가
- 주파수 간섭: GEO 위성·지상 서비스와 동일 대역 사용 시 상호 간섭 발생

> 요약: 핸드오버·군집관리·주파수 공존이 핵심 과제임

## Ⅴ. 개선방안
1. 단기: 빔 추적 안테나와 예측 알고리즘으로 핸드오버 지연을 최소화함
2. 중기: AI 기반 궤도 관제·자율 충돌 회피 시스템으로 운용 비용 절감
3. 장기: ITU 주파수 조정 프레임워크 참여로 GEO·지상 서비스와 간섭 해소

> 요약: 안테나 기술·AI 관제·주파수 협조로 LEO 한계를 극복함

## Ⅵ. 전망
- 발전 방향: D2C(Direct-to-Cell) 기술로 일반 스마트폰의 위성 직접 접속 확대 전망
- 기술사적 판단: 지상 5G/6G와 LEO의 융합이 비지상 네트워크(043 참조) 핵심 축이 될 것임
- 기술사 제언: 우주 쓰레기 저감 규정과 국제 주파수 협조 체계 확립이 선행되어야 함
