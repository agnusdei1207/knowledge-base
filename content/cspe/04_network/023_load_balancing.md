## Ⅰ. 개요
- **정의**: 서비스 앞단에서 유입되는 방대한 대규모 트래픽 부하를 후단의 여러 시스템(서버)으로 분산시키는 스위칭 기술임.
- **배경 및 필요성**: 서버 스케일업 성능 한계 극복 및 다중화 배치를 통한 고가용성(Scale-out) 확보 목적.
- **출제 의도**: 계층별 밸런싱 동작 원리(IP기반 고속 분산 vs 헤더기반 정밀 분산) 및 트래픽 분배 알고리즘 응용력 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **L4 로드 밸런서** | IP 주소 및 TCP/UDP 포트 등 전송 계층 정보만 기반으로 부하를 기계적으로 분할 | 소포 겉면 우편번호만 확인 후 자동 분류 |
| **L7 로드 밸런서** | HTTP URL, 헤더, 쿠키 등 응용 계층 내부 데이터를 파싱해 지능적으로 경로 라우팅 | 편지 내용물과 담당 업무를 확인 후 배정 |
| **분산 스케줄링** | 라운드 로빈(순차), 최소 연결 수(Least Connection) 등 서버 상태 기반 최적 분배 규칙 | 은행 창구 고객 번호표 자동 할당기 |

> 요약: L4 로드밸런싱은 속도와 패킷 처리 중심의 단순 분산, L7은 애플리케이션 데이터 기반의 세밀한 콘텐츠 분산을 수행함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **[L4] 트래픽 유입 검사**: 클라이언트가 가상 IP(VIP)로 요청 시, 로드밸런서가 IP/Port 정보를 확인함.
2. **[L4] 기계적 패킷 전달**: 설정된 알고리즘(순환 등)에 따라 패킷의 도착지 IP/MAC을 변환하여 백엔드로 바로 전달함.
3. **[L7] 세션 대리 수립 및 내부 파싱**: 로드밸런서가 먼저 클라이언트와 세션을 맺고 HTTP 헤더와 URI를 심층 검사함.
4. **[L7] 애플리케이션 라우팅**: /video 경로는 영상 서버 팜으로 분기시키는 등 콘텐츠를 분석해 적절한 백엔드에 요청함.

> 요약: L4는 주소를 변경해 트래픽을 신속하게 배분하고, L7은 세션을 맺은 뒤 내용물을 보고 적임 서버로 유도함.

## Ⅳ. 문제점
- L4 밸런싱의 세션 단절 불일치 (원인: 로그인 정보를 가진 접속 트래픽이 매번 다른 서버로 나뉘어져 로그인 상태 유실)
- L7 밸런서의 극심한 처리 오버헤드 (원인: 모든 데이터의 암호화(SSL) 해제 및 페이로드 심층 검사에 따른 CPU 병목 발생)
- 로드밸런서 인프라 단일 장애점(SPOF) 리스크 (원인: 앞단 밸런서 1대 다운 시 후단의 전체 서버 클러스터 접근 완전 불능 상태)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 세션 유지(Sticky Session) 기법 구성 활성화 (IP 해싱이나 L7 세션 쿠키 삽입으로 한 사용자는 무조건 한 서버로 지속 고정)
- **중기 방안**: [중기] L4/L7 이중화 (VRRP 적용) 및 하드웨어 가속/오프로딩 (밸런서 노드를 이중화 배치하고 SSL 암/복호화 가속기 적용)
- **장기 방안**: [장기] 클라이언트 사이드 로드밸런싱 도입 (서비스 메시 환경에서 각 서비스가 디스커버리를 통해 직접 목적지 서버로 다이렉트 분산 호출)

## Ⅵ. 전망
- 전통적 하드웨어 어플라이언스에서 퍼블릭 클라우드 L7 Ingress 및 컨테이너 소프트웨어 기반 분산 체계로 고도화 중임.
