## Ⅰ. 개요
- 정의: 수많은 이기종 사물(디바이스)을 연결하고, 수집된 데이터를 수집, 저장, 분석하여 애플리케이션에 제공하는 통합 미들웨어 소프트웨어 프레임워크임.
- 배경/필요성: 다양한 제조사와 프로토콜(MQTT, CoAP 등)로 파편화된 IoT 환경에서 일관된 기기 관리와 데이터 활용 표준화 필요.
- 출제 의도: oneM2M 등 국제 표준 기반의 IoT 플랫폼 3계층 구조와 핵심 공통 기능(CSF) 파악.

## Ⅱ. 구성요소
```text
+-----------------------------------+
|      Application Layer (Service)  |
+-----------------------------------+
|      Platform Layer (oneM2M)      |
|  [Device Mgmt] [Data Store] [API] |
+-----------------------------------+
|      Network / Device Layer       |
|   (Sensors, Gateways, MQTT/CoAP)  |
+-----------------------------------+
```
- 구성요소 | 설명 | 비유
  - 디바이스/엣지 계층 | 실제 물리적 환경 데이터를 수집하는 센서와 통신 프로토콜 게이트웨이 | 현장 수집 요원
  - 플랫폼 (공통 서비스) 계층 | 인증, 디바이스 관리, 데이터 저장, 메시지 라우팅 수행 (핵심 허브) | 물류 중앙 허브 터미널
  - 애플리케이션 계층 | 플랫폼 API를 호출하여 스마트홈, 스마트팩토리 등의 서비스를 사용자에게 제공 | 소매점 서비스
> 요약: 이기종 기기의 복잡성을 플랫폼 계층이 숨기고 상위 앱에 표준화된 API를 제공함.

## Ⅲ. 절차
```text
+----------------+      +----------------+      +----------------+
|  1.기기 등록   | ---> |  2.데이터 게시 | ---> |  3.구독/활용   |
+----------------+      +----------------+      +----------------+
```
- 1단계 (기기 등록/인증): IoT 단말이 MQTT/CoAP 프로토콜을 통해 플랫폼에 접속하여 고유 ID를 부여받고 인증을 완료함.
- 2단계 (데이터 수집/저장): 단말이 측정한 온도, 습도 등의 페이로드를 Publish하면, 플랫폼이 이를 시계열 DB에 정규화하여 저장함.
- 3단계 (규칙 및 분석 처리): 플랫폼의 룰 엔진(Rule Engine)이 특정 임계치 초과 시 알람을 발생시키거나 기초 통계를 연산함.
- 4단계 (API 제공/구독): 상위 애플리케이션(스마트폰 앱)이 플랫폼에 Subscribe하여 데이터를 실시간으로 가져가 서비스를 제공함.
> 요약: 하위 기기가 데이터를 플랫폼에 쏘면, 플랫폼이 이를 가공해 상위 앱으로 전달하는 파이프라인임.

## Ⅳ. 문제점
- 1. 플랫폼 종속성(Lock-in): AWS IoT, Azure IoT, 통신사 플랫폼 등 벤더별 독자적 생태계 구축으로 인해 타 플랫폼 간 데이터 연동이 단절됨.
- 2. 중앙 집중형 트래픽 과부하: 수십억 대의 기기가 중앙 클라우드 플랫폼으로 일제히 데이터를 보낼 경우 서버 부하 및 전송 비용 폭증.

## Ⅴ. 개선방안
- 1. 개방형 표준 연동(Inter-working) 기술 확보 (단기): oneM2M, OCF 등의 글로벌 표준 채택을 통해 이기종 플랫폼(예: 가전-통신사) 간 데이터 공유 API 구축.
- 2. 클라우드-엣지 분산 플랫폼 (중장기): 무거운 데이터 전처리 및 즉각 제어 로직을 엣지 게이트웨이로 하방 전개(Offloading)하여 중앙 트래픽 부하 분산.

## Ⅵ. 전망
- 생성형 AI와 결합한 'AIoT 플랫폼'으로 진화하여, 단순 데이터 수집을 넘어 기기들이 자율적으로 상황을 인지하고 대화형으로 동작을 제어하는 환경을 열 것임.
- 데이터 주권 강화 트렌드에 따라 퍼블릭 클라우드 의존도를 낮춘 분산형 블록체인 기반 Web3 IoT 플랫폼 연구도 가속화될 전망임.
