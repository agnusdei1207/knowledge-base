## 미리 알고가기

- DDoS는 많은 공격원이 동시에 트래픽이나 연결 요청을 보내 서비스를 마비시키는 공격임
- SYN Flood는 TCP 연결을 반쯤만 열어 서버의 연결 상태를 소진시키는 공격임
- 증폭 공격은 작은 요청으로 큰 응답을 유도해 피해자에게 대량 트래픽을 보내는 공격임
- 스크러빙은 공격 트래픽을 분리해 정상 패킷만 다시 전달하는 정화 처리임

## Ⅰ. 개요

- **정의/개념**: DDoS 대응은 대량 트래픽과 연결 소진과 반사 증폭 같은 공격을 구간별로 흡수하고 걸러 정상 사용자의 접속을 유지하는 네트워크 방어 체계임
- **배경/필요성**: 인터넷 서비스는 항상 공개돼 있고 공격 도구도 쉬워져 한 지점의 장비만으로는 대량 공격을 버티기 어려우므로, 상위망과 애플리케이션까지 묶은 다층 방어가 필요함

## Ⅱ. 특징

- 대역폭 소진형과 연결 상태 소진형은 방어 위치와 방법이 다름
- 공격이 분산돼 들어오므로 원점 차단보다 우회와 흡수 전략이 더 현실적임
- 정상 이용자와 유사한 패턴이 섞이면 무조건 차단이 서비스 장애로 이어질 수 있음
- 탐지 속도와 우회 전환 속도가 늦으면 방어 장비를 갖춰도 효과가 떨어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | SYN Flood | 증폭 공격 |
|:---|:---|:---|
| 소진 대상 | 서버의 연결 상태와 큐를 소진함 | 회선 대역폭과 상위 장비 처리량을 밀어 올림 |
| 주된 방식 | 대량의 SYN 요청을 보내고 응답을 끝내지 않음 | 위조 출발지 주소로 반사 서버의 큰 응답을 유도함 |
| 방어 위치 | 서버와 로드밸런서와 방화벽 앞단이 중요함 | 통신사 구간과 스크러빙 센터가 중요함 |
| 대표 대응 | SYN 쿠키, 백로그 튜닝, 연결 제한이 유효함 | 출발지 검증, 반사원 차단, 우회 정화가 유효함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 공격원 | 봇넷이나 위조 요청 발신지로 대량 패킷을 생성함 |
| 반사 서버 | 증폭 공격에서 큰 응답을 대신 보내는 장치가 됨 |
| 엣지 라우터 | 우회와 ACL과 속도 제한을 적용하는 첫 관문임 |
| 스크러빙 센터 | 공격 패킷을 걸러 정상 트래픽만 남김 |
| 원본 서비스 | 최종적으로 보호해야 할 서버와 애플리케이션임 |

```text
+--------+    공격 트래픽    +-------------+    우회·정화    +-----------+
| 공격원   | -------------> | 엣지·상위망    | -----------> | 원본 서비스  |
+--------+                  +-------------+                +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[이상 징후 탐지] -> [차단·속도 제한] -> [우회 정화] -> [정상 트래픽 전달] -> [사후 조정]
```

1. **이상 징후 탐지**: 트래픽 급증과 연결 실패와 응답 지연을 감지함
2. **차단·속도 제한**: 엣지에서 1차 필터와 연결 제한을 적용함
3. **우회 정화**: 필요하면 스크러빙 센터로 우회해 공격 패킷을 제거함
4. **정상 트래픽 전달**: 걸러낸 트래픽만 원본 서비스로 전달함
5. **사후 조정**: 필터 정책과 임계값을 다시 다듬음

## Ⅵ. 실무 적용 및 유의점

1. 공개 웹 서비스와 게임 서비스는 대량 트래픽 공격에 노출되기 쉬우므로 통신사 우회 체계와 애니캐스트 분산과 스크러빙 연동을 미리 준비하고 정상 전달 비율과 우회 전환 시간과 응답 지연 증가폭을 같이 확인함
2. 상태 소진형 공격은 서버 앞단에서 먼저 무너질 수 있으므로 반쯤 열린 연결을 버티는 보호 기능과 연결 대기 큐 튜닝과 세션 제한을 함께 적용하고 반쯤 열린 연결 수와 신규 연결 성공률을 계속 봐야 함

## Ⅶ. 결론

DDoS 대응의 핵심은 공격을 완전히 막겠다는 발상보다 어디에서 흡수하고 어디에서 정화할지 계층별 방어 지점을 미리 나누는 데 있음.
