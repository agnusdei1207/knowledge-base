## Ⅰ. 개요
- **정의**: Link State 알고리즘 기반의 IGP 라우팅 프로토콜
- **배경/필요성**: RIP의 홉 수 제한(15)과 느린 수렴을 해결하기 위해 대역폭 기반 메트릭과 빠른 수렴이 필요함
- **비유**: 도시 전체 지도를 공유한 뒤 각자 최단 경로를 계산하는 방식과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Area 기반 계층 구조와 LSA 동작 이해 | Dijkstra 알고리즘과 Area 0 역할 | DR/BDR 선출 목적을 단순 부하분산과 혼동하지 않을 것 |

> 요약: Dijkstra 알고리즘으로 최단 경로를 계산하는 Link State 기반 IGP임

## Ⅱ. 구성요소
```text
OSPF Domain
  +-- Area 0 (Backbone)
  |     +-- ABR --+-- Area 1
  |     +-- ABR --+-- Area 2
  +-- ASBR --> External Network
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| LSDB | 모든 링크 상태 정보를 저장하는 데이터베이스 | 도시 전체 도로 지도 |
| LSA | 링크 상태 변경을 알리는 광고 패킷(Type 1~7) | 도로 공사 알림 전단지 |
| Area | 라우팅 도메인을 분할하는 논리적 단위 | 도시를 구 단위로 나눈 행정구역 |
| DR/BDR | 멀티액세스 네트워크에서 LSA 교환을 대표하는 라우터 | 반장이 공지를 취합·전달하는 역할 |

> 요약: LSDB·LSA·Area·DR 구조로 대규모 망의 효율적 경로 계산을 지원함

## Ⅲ. 절차
```text
Hello 교환 --> 인접 관계 수립 --> LSDB 동기화 --> SPF 계산 --> 라우팅 테이블 갱신
```
- 1단계: Hello 패킷을 주기적으로 교환하여 인접 라우터를 발견함
- 2단계: 2-Way 상태 확인 후 DR/BDR 선출 및 인접 관계(Adjacency)를 수립함
- 3단계: DBD·LSR·LSU 패킷으로 LSDB를 동기화함
- 4단계: Dijkstra SPF 알고리즘으로 최단 경로를 계산하여 라우팅 테이블에 반영함

> 요약: Hello 교환부터 SPF 계산까지 4단계로 최적 경로를 도출함

## Ⅳ. 문제점
- Area 설계 복잡성: 부적절한 Area 분할 시 ABR 부하 집중과 서브옵티멀 경로가 발생함
- SPF 연산 부하: 대규모 LSDB에서 빈번한 토폴로지 변경 시 CPU 사용률이 급증함
- 멀티벤더 호환: 벤더별 구현 차이로 LSA 처리 불일치가 발생할 수 있음

> 요약: Area 설계·SPF 부하·벤더 호환이 운영상 주요 과제임

## Ⅴ. 개선방안
1. 단기: Stub/NSSA Area 적용으로 외부 LSA를 차단하여 ABR 부하를 경감함
2. 중기: SPF Throttling(점진적 지연) 적용으로 연산 빈도를 제어함
3. 장기: Segment Routing 연계로 MPLS 레이블 자동 배포 및 트래픽 엔지니어링을 구현함

> 요약: Area 최적화·SPF 제어·SR 연계로 단계적 개선이 가능함

## Ⅵ. 전망
- 발전 방향: OSPFv3(IPv6)와 Segment Routing 결합으로 차세대 IGP 역할을 수행함
- 기술사적 판단: 엔터프라이즈·ISP 내부망의 표준 IGP로서 당분간 대체 불가한 위치임
- 기술사 제언: Area 설계 원칙과 SR-OSPF 연계 구조를 함께 숙지할 필요
