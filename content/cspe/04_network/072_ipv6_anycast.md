## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 동일한 IP 주소를 여러 대의 노드에 부여하고, 발신자로부터 가장 물리적/논리적으로 가까운 단일 노드로 트래픽을 라우팅하는 통신 방식 |
| **배경/필요성** | 글로벌 분산 서비스(DNS, CDN)의 지연 시간 최소화 및 트래픽 로드밸런싱, 장애 조치(Failover) 필요 |
| **출제 의도** | 유니캐스트/멀티캐스트와 구별되는 애니캐스트의 최단 경로 라우팅 개념 및 서비스 가용성 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Client  | ----> | Router A | ----> | Server 1 |
|          |       | (Closest)|       | (Anycast)|
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 유니캐스트 | 단일 목적지 IP를 향해 1:1로 통신하는 가장 기본적인 방식 | 지정된 수취인 배달 |
| 멀티캐스트 | 특정 그룹에 속한 여러 단말에게 동시에 1:N으로 데이터를 복사 전송 | 사내 그룹 방송 |
| 애니캐스트 | 동일 주소를 가진 그룹 중 가장 근접한(최단 경로) 단일 노드와 1:1 통신 | 가장 가까운 소방서 호출 |

> 요약: 라우팅 메트릭 기반으로 최적 근접 서버를 자동 탐색하여 서비스 응답성을 극대화함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 주소 할당| -> | 경로 광고| -> | 최단 탐색| -> | 트래픽전달|
+----------+    +----------+    +----------+    +----------+
```
1. 주소 할당: 여러 지역의 서버 인터페이스에 동일한 IPv6 애니캐스트 주소 설정
2. 경로 광고: 각 서버와 연결된 라우터들이 BGP나 OSPF를 통해 동일한 주소 대역을 인터넷에 광고
3. 최단 탐색: 클라이언트의 통신 요청 시 라우팅 프로토콜이 가장 홉(Hop) 수가 적은 최단 경로 선출
4. 트래픽전달: 선출된 단일 최적 경로의 서버로만 패킷이 전달되어 가장 빠른 서비스 응답 수행

> 요약: 동일 IP를 다중 광고하고 라우팅 인프라가 자체적으로 최적 경로를 결정하여 연결함

## Ⅳ. 문제점
- 상태 저장(Stateful) 통신인 TCP 환경에서 라우팅 경로가 도중 변경 시 서로 다른 서버로 패킷이 유입되어 세션 단절 (치명적 단점)
- DDoS 공격 발생 시 특정 애니캐스트 노드 근처로 트래픽이 쏠릴 경우 해당 지역 노드 완전 마비 가능성
- 전역 라우팅 테이블(Global BGP)을 활용하므로 기업 내부의 미세한 트래픽 엔지니어링 제어 곤란

## Ⅴ. 개선방안
- [단기] UDP 기반의 상태가 없는(Stateless) 서비스(DNS 등) 위주로 애니캐스트 적용 범위를 제한
- [중기] BGP 정책 튜닝 및 Anycast 노드 간 터널링(GRE) 백업 설정으로 세션 유지 연속성 확보 방안 마련
- [장기] SDN을 접목하여 BGP 트래픽 쏠림을 감지하고 동적으로 라우팅 비용(Metric)을 재조정하는 지능형 관리 체계 확립

## Ⅵ. 전망
- CDN, 루트 DNS, 엣지 컴퓨팅 확산과 맞물려 글로벌 서비스 인프라 구축의 필수 기본 설계로 정착할 전망임
