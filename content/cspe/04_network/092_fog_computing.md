## Ⅰ. 개요
- **정의**: 클라우드와 엣지 사이에 중간 계층을 두어 분산 처리하는 컴퓨팅 모델
- **배경/필요성**: 엣지 노드만으로는 복잡한 집계·상관분석이 어려워 중간 처리 계층이 필요함
- **비유**: 본사(클라우드)와 현장(엣지) 사이에 지역 본부를 두어 중간 판단을 위임하는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지와 클라우드 중간 계층 역할 이해 | 다계층 분산 처리 구조 | Edge Computing(091 참조)과 계층 위치 차이 명확히 구분 |

> 요약: 엣지-클라우드 사이 중간 노드에서 집계·분석을 수행하는 계층적 분산 모델임

## Ⅱ. 구성요소
```text
[IoT] --> [Edge] --> [Fog Node] --> [Cloud]
                        |
                  집계/상관분석
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Fog Node | 라우터·게이트웨이 등에 탑재되어 지역 집계를 수행하는 중간 서버 | 지역 본부 |
| Fog Abstraction Layer | 이기종 엣지 자원을 통합 관리하는 추상화 계층 | 지역 본부 행정실 |
| Fog Orchestrator | Fog 노드 배치·부하 분산·장애 복구를 제어하는 관리 평면 | 지역 본부장 |
| Cloud Tier | 글로벌 학습·장기 보관 등 대규모 연산 담당 | 본사 |

> 요약: IoT-Edge-Fog-Cloud 4계층으로 워크로드를 분산 배치함

## Ⅲ. 절차
```text
엣지 수집 --> Fog 집계 --> 정책 판단 --> 클라우드 보고
```
- 1단계: 엣지 노드가 전처리된 데이터를 Fog 노드로 전달함
- 2단계: Fog 노드에서 다수 엣지 데이터를 집계·상관분석함
- 3단계: 지역 정책 엔진이 임계치 기반 판단·액션을 수행함
- 4단계: 요약 결과와 이상 이벤트만 클라우드로 보고함

> 요약: 엣지 데이터를 중간 계층에서 집계·판단한 뒤 클라우드로 요약 전달함

## Ⅳ. 문제점
- 계층 복잡성: 엣지-포그-클라우드 3계층 간 역할 경계 설정이 어려움
- 표준 부재: 벤더별 포그 플랫폼 상호운용성이 낮음
- 자원 제약: 네트워크 장비에 탑재되므로 CPU·메모리 한계가 존재함

> 요약: 계층 설계·표준화·자원 한계가 주요 과제임

## Ⅴ. 개선방안
1. 단기: 워크로드 프로파일링으로 엣지-포그-클라우드 간 배치 기준 수립
2. 중기: OpenFog 참조 아키텍처 기반 상호운용 표준 적용
3. 장기: 경량 컨테이너·서버리스로 포그 노드 자원 효율 극대화

> 요약: 배치 기준-표준화-경량화 순으로 포그 계층 성숙도를 높여야 함

## Ⅵ. 전망
- 발전 방향: 엣지-포그 경계가 MEC·SASE 등 통합 아키텍처로 수렴 추세
- 기술사적 판단: 스마트시티·산업IoT에서 지역 집계 수요가 지속 존재함
- 기술사 제언: 엣지(091 참조)와 역할 분담 기준을 사전 정의한 아키텍처 설계 필요
