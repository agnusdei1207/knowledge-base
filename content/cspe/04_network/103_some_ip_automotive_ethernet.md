## 미리 알고가기

- 서비스 지향 통신은 기능을 메시지 ID가 아니라 서비스와 메서드 단위로 노출하는 방식임
- 서비스 발견은 어떤 ECU가 어떤 기능을 제공하는지 네트워크에서 찾아내는 절차임
- 메서드 호출은 요청과 응답으로 기능을 수행하는 방식이고 이벤트는 변화가 생길 때 통지를 보내는 방식임
- 자동차 이더넷은 차량 내부에서 고속 데이터 통신을 수행하는 이더넷 기반 네트워크임

## Ⅰ. 개요

- **정의/개념**: SOME/IP는 차량 이더넷 환경에서 ECU 기능을 서비스 단위로 공개하고 호출하고 구독할 수 있게 만든 서비스 지향 통신 미들웨어임
- **배경/필요성**: ADAS와 인포테인먼트와 OTA가 늘면서 고정 메시지 ID 중심 구조만으로는 대용량 데이터와 동적 기능 조합을 다루기 어려워 서비스 수준 통신이 필요해짐

## Ⅱ. 특징

- 기능을 서비스와 메서드와 이벤트로 나눠 표현함
- 서비스 발견 절차가 있어 ECU 위치가 바뀌어도 논리 기능 기준으로 연결할 수 있음
- 이더넷과 IP를 기반으로 TCP·UDP 전송과 기존 IP 도구를 활용함
- 서비스 수가 많아지면 발견 트래픽과 버전 호환 관리가 복잡해질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | CAN 메시지 통신 | SOME/IP |
|:---|:---|:---|
| 통신 모델 | 메시지 ID 중심 브로드캐스트 | 서비스와 메서드 중심 통신 |
| 데이터 크기 | 8바이트 이하의 제어 데이터 중심임 | IP 패킷으로 서비스 데이터와 이벤트를 전달함 |
| 기능 탐색 | 사전 정의된 ID 매핑에 의존함 | 서비스 발견으로 동적으로 찾을 수 있음 |
| 적합한 환경 | 저지연 제어망 | ADAS, 인포테인먼트, 소프트웨어 중심 차량 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 서비스 제공자 | 기능을 공개하고 요청을 처리하는 ECU임 |
| 서비스 소비자 | 필요한 기능을 찾고 호출하거나 이벤트를 구독하는 ECU임 |
| 서비스 발견 모듈 | 제공 가능한 서비스 목록과 위치를 광고하고 탐색함 |
| 전송 계층 | TCP나 UDP를 사용해 요청, 응답, 이벤트를 전달함 |
| 스위치와 QoS 정책 | 차량 이더넷에서 대역폭과 우선순위를 관리함 |

```text
+-------------+    +----------------+    +-------------+
| 서비스 제공 ECU | -> | 서비스 발견·전송 계층 | -> | 소비 ECU      |
+-------------+    +----------------+    +-------------+
        |                                         |
        +-------------- 메서드·이벤트 ------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 서비스 광고    | -> | 서비스 탐색    | -> | 연결 수립      | -> | 호출·이벤트 처리 | -> | 상태 감시      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **서비스 광고**: 제공 ECU가 자신의 서비스 정보를 네트워크에 알림
2. **서비스 탐색**: 소비 ECU가 필요한 서비스를 찾아 위치와 버전을 확인함
3. **연결 수립**: 선택한 서비스와 세션을 맺음
4. **호출과 이벤트 처리**: 메서드 요청이나 이벤트 구독을 수행함
5. **상태 감시**: 응답 시간과 연결 상태를 보고 서비스 품질을 관리함

## Ⅵ. 실무 적용 및 유의점

1. ADAS와 인포테인먼트 도메인은 SOME/IP가 잘 맞지만 서비스 발견 트래픽이 많아지면 부팅 지연이 생길 수 있으므로 서비스 범위를 정리하고 발견 성공률과 초기 연결 시간을 확인해야 함
2. 동일 기능의 버전이 섞이면 호출 실패가 늘 수 있으므로 서비스 인터페이스 버전 정책을 엄격히 관리하고 메서드 오류율과 응답 지연 변화를 계속 봐야 함

## Ⅶ. 결론

SOME/IP는 차량 통신을 메시지 중심에서 서비스 중심으로 바꾸는 기술이므로 대역폭보다도 서비스 발견과 인터페이스 관리 체계가 성패를 가름함
