## 미리 알고가기

- 오버레이는 물리망 위에 논리적으로 만든 가상 네트워크임
- 언더레이는 실제 IP 라우팅과 물리 연결을 담당하는 기반망임
- VNI는 VXLAN 가상 네트워크를 구분하는 24비트 식별자임
- VTEP는 VXLAN 캡슐화를 수행하는 터널 종단 장비임

## Ⅰ. 개요

- **정의/개념**: VXLAN은 L2 프레임을 UDP와 IP로 캡슐화해 L3 언더레이 위에서 오버레이 네트워크를 구현하는 터널링 기술임
- **배경/필요성**: 클라우드와 멀티테넌트 환경에서는 VLAN 4천 개 한계와 L2 연장 제약이 문제이므로, 더 많은 가상 네트워크를 만들고 L3 구간을 넘어 VM과 컨테이너를 유연하게 이동시킬 방법이 필요함

## Ⅱ. 특징

- 24비트 VNI를 사용해 VLAN보다 훨씬 많은 가상 네트워크를 만들 수 있음
- L3 언더레이 위에서 L2 오버레이를 제공해 물리 토폴로지 제약을 줄임
- VTEP가 캡슐화와 역캡슐화를 수행해 엔드포인트 이동성을 지원함
- 제어 평면이 없으면 플러딩 비중이 커지므로 EVPN 같은 제어 기술과 결합할수록 확장성이 좋아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | VLAN | VXLAN |
|:---|:---|:---|
| 식별자 규모 | 12비트 VLAN ID를 사용함 | 24비트 VNI를 사용하여 VLAN보다 많은 세그먼트를 구분함 |
| 동작 범위 | 기본적으로 L2 도메인 내부 분리에 적합함 | L3 언더레이를 통과하는 오버레이 확장에 적합함 |
| 이동성 지원 | 데이터센터 간 L2 확장에는 제약이 큼 | 가상머신과 컨테이너의 위치 이동을 더 유연하게 지원함 |
| 운영 고려사항 | 구조가 단순하지만 확장성이 낮음 | MTU, VTEP, 제어 평면 설계까지 함께 고려해야 함 |

> 요약: VLAN은 L2 링크 범위의 세그먼트를 구분하고 VXLAN은 L3 언더레이 위에서 VNI 단위 가상 세그먼트를 연결함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 오버레이 엔드포인트 | VM, 컨테이너, 서버처럼 가상 네트워크를 실제로 사용하는 종단임 |
| VTEP | 오버레이 프레임을 언더레이 패킷으로 캡슐화하고 다시 해제하는 터널 종단임 |
| VNI | 어떤 가상 네트워크 소속인지 식별해 테넌트 분리를 보장하는 값임 |
| 언더레이 IP 패브릭 | VTEP 간 IP 도달성과 ECMP 경로를 제공하는 물리 기반망임 |
| 제어 평면 | EVPN 같은 방식으로 MAC, IP 위치 정보를 교환해 플러딩을 줄이는 기능임 |

```text
+-------------+     +-------------+     +----------------+     +-------------+
| 오버레이 단말  | --> | VTEP         | --> | 언더레이 IP 패브릭 | --> | 원격 VTEP      |
+-------------+     +-------------+     +----------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| L2 프레임 생성  | --> | VNI 조회와 캡슐화   | --> | 언더레이 IP 전달    | --> | 역캡슐화·전달    |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **L2 프레임 생성**: 가상 단말이 원래의 이더넷 프레임을 생성함
2. **VNI 조회와 캡슐화**: VTEP가 해당 가상 네트워크의 VNI를 확인하고 UDP, IP 헤더를 덧붙임
3. **언더레이 IP 전달**: 언더레이 라우팅이 원격 VTEP까지 캡슐화된 패킷을 전달함
4. **역캡슐화와 전달**: 원격 VTEP가 헤더를 제거하고 목적 단말에 원래 프레임을 보냄

## Ⅵ. 실무 적용 및 유의점

1. 멀티테넌트 데이터센터에서 VLAN 수와 L2 확장 범위를 넘겨야 할 때는 VXLAN을 적용하되 오버레이 헤더만큼 MTU 여유가 없으면 단편화가 생기므로 언더레이 점보 프레임과 경로 MTU를 점검하고 단편화 건수와 처리량 변화로 확인함
2. VXLAN만 단독으로 쓰는 환경에서는 BUM 플러딩이 커질 수 있으므로 대규모 확장 전에는 EVPN 제어 평면을 결합하고 MAC 이동 이벤트 수와 브로드캐스트 비율로 확인함

## Ⅶ. 결론

VXLAN의 핵심은 L3 물리망 위에 대규모 L2 가상망을 유연하게 올리는 데 있으므로 MTU와 제어 평면 설계가 확장성의 핵심 기준임.
