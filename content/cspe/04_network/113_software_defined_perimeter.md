# 📖 【암기용】 개념 완전 이해

> 목적: SDP를 제로트러스트 접근의 기술 구조로 이해하고, 숨김·인증·동적 연결의 의미를 구분하게 만든다.

## 한눈에
- **개요**: SDP는 인증 전에는 서비스 위치를 숨기고, 허가된 사용자에게만 동적 접속 경로를 여는 보안 경계 모델이다.
- **왜 필요한가**: 방화벽 포트가 인터넷에 노출되면 스캔, 취약점 탐색, 계정 대입 공격의 대상이 된다.
- **핵심 직관**: 주소를 공개한 뒤 문 앞에서 막는 방식이 아니라, 초대받은 사람에게만 주소와 문을 동시에 알려주는 방식이다.

## 깊이 이해
- **배경·문제의식**: 클라우드와 원격근무에서는 자산 위치가 분산되어 고정 경계 방화벽만으로 접근을 통제하기 어렵다.
- **작동 원리**: SDP Controller가 신원과 단말 상태를 평가하고, SDP Gateway가 허가된 세션에 대해서만 애플리케이션 연결을 허용한다.
- **비유**: 비공개 행사장에서 초대장을 검증한 뒤 참석자별로 다른 출입문 위치를 알려주는 절차와 같다.
- **구체 예시**: 관리 포털을 인터넷에 공개하지 않고, MFA와 단말 점검을 통과한 운영자에게만 단기 세션을 열어 SSH·HTTPS 접근을 중계한다.
- **흔한 오해·주의점**: SDP는 방화벽을 없애는 기술이 아니라, 방화벽 앞단에 신원 기반 동적 접근 절차를 추가하는 구조다.

## 연결 개념
- ZTNA - SDP 원리를 상용 원격접속 서비스로 구현
- SASE/SSE - SDP 기능을 클라우드 보안 서비스와 통합
- Microsegmentation - 허가 세션 이후 내부 이동 범위 제한

# 📝 【답안용】 시험 답안 템플릿

> 목적: SDP 답안은 "소프트웨어로 경계 구현"이라는 설명을 넘어 인증 전 비노출과 동적 정책 집행을 써야 한다.
> 핵심: Controller, Gateway, Client, IdP의 역할과 SPA, mTLS, 정책 로그를 연결한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SDP는 사용자·단말 검증 전에는 리소스를 노출하지 않고, 검증 후 정책 기반 세션을 생성하는 접근 경계이다.
> 2. **가치**: 인터넷 스캔 표면을 줄이고, 관리망·업무 앱·클라우드 자원 접근을 신원 중심으로 통제한다.
> 3. **판단 포인트**: 인증 전 비노출, 동적 연결, 세션 로그, 기존 VPN·방화벽과의 공존 여부를 함께 검토한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 제로트러스트 구조 이해 확인 | Controller, Gateway, Client, IdP 역할 | SDP를 SDN 또는 VPN으로만 설명 |
| 공격면 축소 방식 확인 | 인증 전 비노출, SPA, mTLS, 아웃바운드 커넥터 | 포트 차단만 쓰고 정책 평가 누락 |
| 적용 설계 역량 확인 | 관리망, 운영자 접근, 클라우드 앱 보호 | 로그·감사·세션 종료 기준 누락 |

> 요약: SDP는 네트워크 위치보다 신원과 단말 상태로 접근 경계를 동적으로 만드는 기술이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 인증 후 경계를 여는 모델
- 배경: 클라우드와 원격근무로 고정 방화벽 경계만으로 자산 접근 통제가 어려움.
- 필요성: 인증 전 서비스 비노출로 포트 스캔과 취약점 탐색 기회를 줄임.
- 판단 기준: 인터넷 노출 관리 포털, 운영자 SSH, 내부 웹 앱에 우선 적용함.

---

## Ⅱ. 구조 및 구성요소

```text
Client -> IdP/MFA -> SDP Controller -> Policy Decision
       -> SDP Gateway/Connector -> Protected App
       +-> Device Posture -> Log/SIEM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SDP Client | 사용자 인증 요청과 단말 상태 정보를 제출 | 인증서, 에이전트 무결성, OS 패치 확인 |
| IdP/MFA | 사용자 신원과 인증 강도를 검증 | SAML, OIDC, FIDO2 연계 |
| SDP Controller | 정책 판단과 세션 허가를 수행 | 사용자, 단말, 위치, 시간 조건 평가 |
| SDP Gateway | 허가된 세션만 보호 자원에 중계 | 아웃바운드 커넥터로 인바운드 노출 축소 |
| Log/SIEM | 정책 결과와 세션 접속 증적을 수집 | 감사 추적과 이상 행위 탐지 |

> 요약: SDP는 Controller가 판단하고 Gateway가 연결을 열며, IdP와 단말 상태가 정책 입력이 된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접속 전 비노출 -> 클라이언트 인증 -> 단말 상태 제출
-> 정책 평가 -> 게이트웨이 세션 생성 -> 앱 접속 -> 로그 기록 -> 세션 만료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 보호 자원은 인터넷 스캔에 응답하지 않음 | 외부 포트 스캔 결과, DNS 노출 |
| 2 | 사용자는 IdP와 MFA를 통해 신원을 증명 | MFA 성공, 인증서 유효성 |
| 3 | 단말 상태와 접속 맥락을 Controller가 평가 | EDR 동작, 국가, 시간대 |
| 4 | Gateway가 허가 앱 세션만 생성 | mTLS, 세션 TTL, 앱 ID |
| 5 | 세션 종료 후 로그가 SIEM에 저장 | 사용자, 앱, 정책, 결과 기록 |

> 요약: SDP는 리소스를 먼저 숨기고, 인증·정책 평가 후 필요한 세션만 일시적으로 생성한다.

---

## Ⅳ. 특징

| 구분 | 전통 경계 보안 | SDP 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 노출 방식 | IP·포트 공개 후 방화벽 차단 | 인증 전 리소스 비노출 | SPA, mTLS, outbound connector |
| 신뢰 기준 | 내부망 위치 중심 | 사용자·단말·상황 중심 | IdP, EDR posture, risk score |
| 접속 단위 | 네트워크 대역 | 애플리케이션 세션 | app ID, session TTL |
| 감사 증적 | 방화벽 로그 중심 | 사용자별 정책 결정 로그 | SIEM correlation, UEBA |

> 요약: SDP는 접속 전 비노출과 접속 후 세션 단위 정책으로 고정 경계 보안의 노출 문제를 줄인다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | VPN/방화벽 | SDP | 선택 기준 |
|:---|:---|:---|:---|
| 보호 대상 | 네트워크 대역 | 애플리케이션, 관리 포트 | 앱 단위 권한 분리 필요성 |
| 통제 위치 | 경계 장비 | Controller와 Gateway | 클라우드·재택 분산 환경 |
| 공격면 | 게이트웨이와 포트 노출 | 인증 전 비응답 | 외부 스캔 탐지 빈도 |
| 전환 비용 | 기존 장비 유지 | IdP·단말·앱 연동 필요 | 앱 온보딩 규모 |

> 요약: SDP는 인터넷 노출 관리 서비스와 사용자별 권한 차이가 큰 업무에 먼저 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 정책 우회 | 로컬 계정, 우회 포트 잔존 | 우회 경로 차단, 방화벽 룰 정리 | 외부 노출 포트 수 |
| Controller 장애 | 정책 판단 지점 집중 | 이중화, 지역별 PoP, 캐시 정책 | 정책 응답 p95, 장애 시간 |
| 단말 신뢰 오류 | EDR 미설치 또는 상태 위조 | 인증서 바인딩, posture 검증 | 미준수 단말 차단 건수 |
| 감사 누락 | 세션 로그 포맷 불일치 | SIEM 정규화, 공통 사용자 ID | 로그 수집 성공률 |

> 요약: SDP 리스크는 우회 경로, 정책 지점 장애, 단말 검증, 로그 정합성으로 나누어 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 노출 표면 | 외부 공개 관리 포트 0개 | ASM, 포트 스캔 |
| 정책 응답 | 접근 판단 p95 500ms 이하 | Controller 메트릭 |
| 세션 통제 | 세션 TTL과 사용자별 앱 매핑 100% | 정책 내보내기, CMDB 대조 |
| 탐지 지표 | 비정상 접근 MTTD 10분 이하 | SIEM rule, UEBA |

> 요약: SDP 운영 효과는 외부 노출 포트, 정책 응답, 세션 통제, 탐지 시간으로 측정한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 인터넷 노출 관리 포털과 SSH 접근을 SDP Gateway 뒤로 이전하고, 기존 인바운드 방화벽 허용 규칙을 제거함.
2. IdP, MFA, EDR posture, 사용자 그룹을 SDP Controller 정책 입력으로 연결하고 앱별 세션 TTL을 설정함.
3. Controller와 Gateway 로그를 SIEM으로 수집하고, 실패 인증·비정상 국가·반복 차단 이벤트를 탐지 규칙으로 등록함.

**결론 (2줄):**
- 기술사 판단: 외부 노출 포트 축소와 앱별 접근 통제가 목표이면 SDP를 적용하고, 대역 라우팅이 필요하면 VPN을 병행함.
- 향후 방향: SDP는 ZTNA, SASE, SSE 서비스의 핵심 접근 제어 기능으로 흡수되어 운영됨.

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "SDP를 설명하시오" | 인증 전 비노출부터 세션 생성까지 흐름 | Controller·Gateway 역할 |
| 요구사항 명시형 | "제로트러스트 접근 설계를 제시하시오" | IdP·EDR·SIEM 연동 절차 | 노출 표면, 정책, 지표 |

> 요약: 설명형은 SDP 원리를, 설계형은 자산 숨김과 정책 집행 구조를 중심으로 쓴다.
