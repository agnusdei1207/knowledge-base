## 미리 알고가기

- SDP는 인증 전에는 서비스를 보이지 않게 숨기고 허가된 세션만 열어 주는 접근 모델임
- 제어 평면은 누가 접속할지 판단하는 영역임
- 데이터 평면은 실제 트래픽이 흐르는 영역임
- 마이크로 세그멘테이션은 작은 단위로 접근 범위를 나누는 통제 방식임

## Ⅰ. 개요

- **정의/개념**: SDP는 사용자와 기기를 먼저 검증한 뒤 정책에 맞는 서비스에만 동적으로 접속 경로를 열어 주는 소프트웨어 기반 보안 경계 모델임
- **배경/필요성**: 고정된 외부 노출 주소와 광범위한 원격 접속은 공격 표면을 키우므로, 서비스 위치를 숨기고 허가된 세션만 짧게 열어 주는 방식이 필요해짐

## Ⅱ. 특징

- 인증 전에는 서비스가 잘 드러나지 않아 스캔과 무차별 공격을 줄일 수 있음
- 네트워크 전체 대신 서비스 단위로 접근을 나눌 수 있음
- 제어 평면과 데이터 평면을 분리해 정책 변경을 유연하게 처리함
- 신원 체계와 자산 목록이 부정확하면 통제 효과가 급격히 떨어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 경계 보안 | SDP |
|:---|:---|:---|
| 서비스 노출 | 외부에서 주소와 포트가 보이기 쉬움 | 인증 전에는 서비스가 숨겨짐 |
| 접근 범위 | 네트워크 단위 허용이 많음 | 서비스 단위로 세밀하게 허용함 |
| 정책 기준 | IP와 포트 중심인 경우가 많음 | 사용자, 기기, 서비스 정책을 함께 봄 |
| 적합 환경 | 고정 내부망 보호에 익숙함 | 클라우드와 원격 접속 환경에 유리함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 단말 | 접속 요청을 보내는 주체임 |
| SDP 컨트롤러 | 신원과 정책을 확인해 세션 허용 여부를 판단함 |
| SDP 게이트웨이 | 허가된 세션의 실제 통신 경로를 열어 줌 |
| 인증 체계 | 사용자와 기기 상태를 검증함 |
| 보호 자원 | 내부 애플리케이션과 관리 시스템 같은 대상임 |

```text
+--------+    인증 요청    +---------------+    정책 허용    +--------------+
| 사용자   | -----------> | SDP 컨트롤러     | -----------> | SDP 게이트웨이 |
+--------+               +---------------+               +--------------+
     \______________________________________________________________/
                         허가된 경우에만 보호 자원 접속
```

## Ⅴ. 원리 및 절차 흐름도

```text
[접속 요청] -> [신원 확인] -> [정책 판단] -> [세션 경로 생성] -> [접속 종료]
```

1. **접속 요청**: 사용자가 보호 자원 접속을 시도함
2. **신원 확인**: 계정과 기기 조건과 인증 결과를 확인함
3. **정책 판단**: 어떤 서비스까지 허용할지 결정함
4. **세션 경로 생성**: 허가된 경우에만 동적 경로를 열어 줌
5. **접속 종료**: 세션이 끝나면 경로와 권한을 회수함

## Ⅵ. 실무 적용 및 유의점

1. 외부 관리자 접속과 중요 운영 시스템 보호에는 SDP가 공격 표면을 크게 줄일 수 있지만 자산 식별이 빠지면 보호 사각지대가 생기므로 서비스 목록과 정책 태깅을 함께 관리하고 외부 스캔 노출 건수와 허가되지 않은 접근 시도를 같이 확인함
2. 사용자와 기기 검증이 느리거나 불안정하면 접속 품질이 떨어지므로 인증 체계와 단말 상태 수집 경로를 안정화하고 접속 성공률과 정책 판정 지연과 세션 종료 누락 건수를 계속 봐야 함

## Ⅶ. 결론

SDP의 핵심은 경계를 넓게 두는 대신 허가된 세션이 필요한 순간에만 짧게 열어 공격 표면과 접근 범위를 함께 줄이는 데 있음.
