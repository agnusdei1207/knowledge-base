## Ⅰ. 개요
- **정의**: 지리적으로 분산된 엣지 서버에 콘텐츠를 캐싱하여 사용자 근접 위치에서 제공하는 네트워크임
- **배경/필요성**: 원본 서버와 사용자 간 물리적 거리가 멀수록 지연이 증가하므로 콘텐츠를 분산 배치할 필요가 있음
- **비유**: 본사 창고 대신 각 지역 편의점에 인기 상품을 미리 배치해 두는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 캐싱 전략과 DNS 기반 라우팅 원리 | 엣지-오리진 구조, 캐시 히트율 | 동적 콘텐츠 가속(DSA)도 언급 필요 |

> 요약: 엣지 캐싱으로 사용자 근접 지점에서 콘텐츠를 제공하여 지연을 줄이는 분산 네트워크임

## Ⅱ. 구성요소
```text
User --> DNS --> Edge Server (Cache Hit? Yes --> 응답)
                              (Cache Miss? --> Origin Server --> 응답 + 캐시 저장)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Edge Server | 사용자 근접 PoP에 위치하여 캐싱된 콘텐츠를 제공하는 서버 | 지역 편의점 |
| Origin Server | 원본 콘텐츠를 보유한 원천 서버 | 본사 창고 |
| DNS Routing | 사용자 위치 기반으로 최적 엣지를 선택하는 DNS 응답 로직 | 가장 가까운 매장 안내 |
| Cache Policy | TTL·Purge·Invalidation 규칙으로 캐시 갱신을 제어함 | 상품 유통기한 관리 |

> 요약: DNS가 최적 Edge를 선택하고, Edge가 캐시 히트 시 즉시 응답, 미스 시 Origin에서 조회함

## Ⅲ. 절차
```text
DNS 질의 --> 엣지 선택 --> 캐시 조회 --> 히트/미스 처리
```
- 1단계: 사용자 DNS 질의 시 CDN DNS가 지리적으로 가장 가까운 엣지 서버 IP를 응답함
- 2단계: 엣지 서버가 요청을 수신하고 로컬 캐시를 조회함
- 3단계: 캐시 히트 시 즉시 응답하고, 미스 시 Origin Server에서 콘텐츠를 가져옴
- 4단계: Origin 응답을 사용자에게 전달하면서 엣지 캐시에 저장하여 후속 요청에 대비함

> 요약: DNS 기반 엣지 선택 → 캐시 조회 → 히트/미스 분기 → 캐시 저장의 흐름임

## Ⅳ. 문제점
- 캐시 일관성: 원본 갱신 후에도 TTL 만료 전까지 구버전이 제공됨 — 데이터 정합성 저하
- 동적 콘텐츠 한계: 개인화·실시간 데이터는 캐싱이 어려워 CDN 효과가 제한됨
- 비용 증가: 글로벌 PoP 운영과 대역폭 과금으로 트래픽 증가 시 비용이 비례 상승함

> 요약: 캐시 일관성, 동적 콘텐츠 한계, 운영 비용이 주요 과제임

## Ⅴ. 개선방안
1. 단기: Cache Purge API와 버전 쿼리스트링으로 즉시 무효화 적용
2. 중기: DSA(Dynamic Site Acceleration) 기술로 동적 콘텐츠 경로를 최적화함
3. 장기: 엣지 컴퓨팅 기능 결합으로 연산을 엣지에서 처리하여 비용 대비 효율을 향상함

> 요약: 캐시 무효화, DSA, 엣지 컴퓨팅 결합으로 단계별 개선이 가능함

## Ⅵ. 전망
- 발전 방향: 엣지에서 서버리스 함수를 실행하는 Edge Computing 플랫폼으로 확장 중임
- 기술사적 판단: 5G·IoT 확산으로 엣지 처리 수요가 증가하여 CDN의 역할 범위가 확대됨
- 기술사 제언: 콘텐츠 유형별 캐싱 전략 수립과 비용 최적화 모델 설계가 필요함
