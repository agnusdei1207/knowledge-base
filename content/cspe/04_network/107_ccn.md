## Ⅰ. 개요
- 정의: 통신의 중심을 호스트(IP 주소)에서 데이터(콘텐츠 이름)로 전환하여, 위치와 관계없이 콘텐츠 자체를 라우팅하고 캐싱하는 미래형 네트워크 아키텍처임. (ICN의 대표적 모델)
- 배경/필요성: 현대 트래픽의 80% 이상이 멀티미디어 소비 목적인 상황에서, 중복 데이터 전송으로 인한 IP 망 대역폭 고갈 해결 필요.
- 출제 의도: 호스트 중심에서 데이터 중심으로의 패러다임 변화와 인네트워크 캐싱(In-Network Caching) 개념 파악.

## Ⅱ. 구성요소
```text
+----------------+      +----------------+      +----------------+
|   Consumer     | ---> |   CCN Router   | ---> |   Publisher    |
| (Interest Pkt) |      | (CS, PIT, FIB) |      |   (Data Pkt)   |
+----------------+      +----------------+      +----------------+
```
- 구성요소 | 설명 | 비유
  - Content Store (CS) | 라우터 내부에 통과하는 데이터를 임시 저장하는 캐시 공간 | 편의점 재고 창고
  - PIT (Pending Interest Table) | 데이터 요청이 들어온 인터페이스(경로)를 기억하는 테이블 | 배달 예약 명부
  - FIB (Forwarding Info Base) | 콘텐츠 이름의 접두사를 기반으로 요청을 전달할 경로 테이블 | 우편번호 책
> 요약: 라우터가 IP 주소가 아닌 데이터 이름을 인식하고, 중간 라우터에서 데이터를 직접 반환함.

## Ⅲ. 절차
```text
+----------------+      +----------------+      +----------------+
|  1.Interest 발송| ---> |  2.캐시 확인   | ---> |  3.데이터 반환 |
+----------------+      +----------------+      +----------------+
```
- 1단계 (요청/Interest): 사용자가 원하는 콘텐츠의 '이름(/youtube/video/123)'이 담긴 Interest 패킷을 브로드캐스트함.
- 2단계 (라우터 검색): 라우터가 수신 후 CS(캐시)를 검사하여 데이터가 있으면 즉시 반환하고, 없으면 PIT에 요청 경로를 기록함.
- 3단계 (요청 전송): FIB를 참조하여 원본 서버(Publisher) 방향으로 Interest 패킷을 포워딩함.
- 4단계 (데이터 응답): 원본 서버(또는 캐시 보유 라우터)가 Data 패킷을 응답하면, PIT의 역경로를 따라 사용자에게 반환되며 경유 라우터 CS에 저장됨.
> 요약: 콘텐츠 이름으로 요청하면 네트워크 중간 라우터나 원본 서버가 역경로로 데이터를 제공함.

## Ⅳ. 문제점
- 1. 라우터 하드웨어 제약: 모든 패킷을 콘텐츠 이름(가변 길이 스트링)으로 검색해야 하므로 메모리와 라우팅 연산 부하가 극심함.
- 2. 보안 패러다임 혼란: IP 기반의 방화벽/접근 제어가 불가하며, 데이터 자체에 대한 암호화/서명 관리 메커니즘의 복잡성이 큼.

## Ⅴ. 개선방안
- 1. 해시 기반 고속 룩업 적용 (단기): 계층적 이름 구조 대신 고정 길이의 해시값을 사용하여 라우팅 테이블 검색 속도 향상.
- 2. 데이터 중심 보안(Data-Centric Security) 도입 (중장기): 콘텐츠 자체에 생산자의 전자 서명을 결합하여 어떤 경로로 받든 무결성을 검증하는 체계 구축.

## Ⅵ. 전망
- 전면적인 인터넷 코어 교체보다는, 엣지 컴퓨팅이나 IoT, 차량 통신(V2V) 등 폐쇄적/특수 목적 네트워크에 하이브리드 형태로 우선 도입될 것임.
- 5G/6G 환경의 네트워크 슬라이싱 기술과 결합하여 미디어 전송 특화 슬라이스 망 아키텍처로 활용도가 높아질 전망임.
