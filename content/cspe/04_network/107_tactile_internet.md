# 📖 【암기용】 개념 완전 이해

> 목적: 촉각 인터넷을 초저지연·고신뢰 네트워크 관점에서 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사람의 촉각·제어 반응을 원격지에 전달하기 위한 ms급 네트워크
- **왜 필요한가**: 원격 로봇수술, 원격제어, 협동로봇은 영상만 전달해서는 충분하지 않고 힘·압력·위치 피드백이 지연 없이 돌아와야 한다.
- **핵심 직관**: 손으로 물체를 만졌을 때 느낌이 늦게 오면 제어가 흔들리므로, 네트워크가 사람의 신경 반응처럼 짧은 왕복 시간을 제공해야 한다.

## 깊이 이해
- **배경·문제의식**: 기존 인터넷은 best-effort라 지연·손실·지터가 변동한다. 촉각 인터넷은 5G URLLC, Edge Computing, TSN, 네트워크 슬라이싱을 결합해 1ms급 무선 구간과 높은 신뢰도를 목표로 한다.
- **작동 원리**: 촉각 센서가 힘·위치 데이터를 생성하고 Edge가 제어 루프를 가까운 위치에서 처리한다. 네트워크는 우선순위, 중복 경로, 짧은 TTI, 예약 자원으로 지연 상한을 낮춘다.
- **비유**: 원격 조종 자동차를 눈으로만 보는 것이 아니라 핸들이 미끄러지는 느낌까지 즉시 전달받는 구조와 같다.
- **구체 예시**: 원격 로봇 제어에서 위치·힘 피드백을 1ms~10ms 왕복 지연 범위로 유지하지 못하면 제어기가 과보정하여 진동이 발생할 수 있다.
- **흔한 오해·주의점**: 1ms는 전체 인터넷 경로에서 항상 보장되는 수치가 아니다. 무선 접속, Edge 위치, 코어망, 애플리케이션 처리 시간을 합한 예산으로 봐야 한다.

## 연결 개념
- 5G URLLC — 초저지연·고신뢰 무선 통신
- Edge Computing — 제어 루프 근접 처리
- TSN — 유선 구간 결정형 전달

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 촉각 인터넷은 대역폭보다 왕복 지연, 지터, 신뢰도, Edge 배치가 핵심인 폐루프 제어 네트워크이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 촉각 인터넷은 촉각·힘·위치 피드백을 원격 제어 루프에 전달하기 위한 초저지연·고신뢰 네트워크이다.
> 2. **가치**: 원격 로봇, 원격 수술, 산업 제어에서 사람 또는 제어기가 느끼는 반응 시간을 ms 단위로 관리한다.
> 3. **판단 포인트**: 5G URLLC, Edge, TSN, 슬라이싱을 조합하고 지연 예산을 접속망·전송망·처리시간으로 분해해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 초저지연 네트워크 이해 확인 | RTT, jitter, reliability, URLLC, Edge | 속도 중심으로 설명 |
| 적용 구조 판단 확인 | 센서, haptic codec, Edge controller, actuator | 영상 스트리밍과 동일시 |
| 한계와 리스크 확인 | 지연 예산, 경로 이중화, 안전 정지 | 1ms 보장을 전 구간에 단정 |

> 요약: 촉각 인터넷 답안은 폐루프 제어 지연 예산과 신뢰도 확보 방안을 분리해 써야 한다.

## Ⅰ. 개요 및 필요성

- 개요: ms급 촉각 제어망
- 배경: 원격 제어는 영상·음성 지연보다 힘·위치 피드백 지연이 제어 안정성에 직접 영향을 줌.
- 필요성: 로봇·수술·산업 제어에서 RTT 1ms~10ms, 높은 신뢰도, 낮은 jitter를 목표로 네트워크를 설계해야 함.
- 범위: 5G URLLC, MEC/Edge, TSN, haptic codec, 안전 제어를 함께 판단함.

---

## Ⅱ. 구조 및 구성요소

```text
Human/Controller -> Haptic Device -> 5G URLLC/TSN -> Edge Controller -> Remote Robot
Remote Sensor -> Haptic Feedback -> Edge -> Network Slice -> User Device
Safety Logic -> local fallback / emergency stop
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Haptic Device | 힘·위치 입력과 촉각 출력 | sampling 1kHz 검토 |
| URLLC/TSN Network | 저지연·예약 자원 전달 | slicing, QoS, Qbv |
| Edge Controller | 제어 루프 근접 처리 | MEC 배치 거리 |
| Remote Robot | 명령 실행과 센서 피드백 생성 | actuator safety |
| Safety Logic | 지연 초과 시 안전 상태 전환 | local fallback |

> 요약: 촉각 인터넷 구조는 촉각 단말, 저지연 네트워크, Edge 제어기, 원격 장치, 안전 로직이 폐루프를 형성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
촉각 입력 측정 -> 패킷화/압축 -> URLLC/TSN 전달
-> Edge 제어 계산 -> 로봇 구동 -> 힘/위치 피드백
-> 지연 초과 감지 -> 안전 정지 또는 로컬 제어
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 힘·위치·촉각 데이터를 샘플링 | sampling rate, quantization |
| 2 | 저지연 코덱과 우선순위 큐 적용 | packetization delay |
| 3 | URLLC/TSN 경로로 전송 | RTT, jitter, loss |
| 4 | Edge가 제어 명령을 계산 | processing time |
| 5 | 피드백 지연 초과 시 안전 로직 실행 | timeout, fail-safe count |

> 요약: 촉각 인터넷은 입력, 전송, Edge 처리, 피드백, 안전 전환의 전체 왕복 지연을 예산으로 관리한다.

## Ⅳ. 특징

| 구분 | 일반 실시간 스트리밍 | 촉각 인터넷 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 목표 | 영상·음성 전달 | 힘·위치 폐루프 제어 | RTT 1ms~10ms 목표 |

| 처리 위치 | 클라우드 중심 | Edge/MEC 근접 처리 | 거리·처리시간 예산 |
| 안전성 | 재생 품질 저하 | 과보정·오작동 위험 | fail-safe, local fallback |

> 요약: 촉각 인터넷은 콘텐츠 전송이 아니라 지연·지터가 제어 안정성에 영향을 주는 폐루프 네트워크이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 촉각 인터넷 | 선택 기준 |
|:---|:---|:---|:---|
| 무선망 | eMBB 중심 | URLLC slice | 지연·신뢰도 요구 |
| 처리 위치 | 원격 클라우드 | MEC/Edge | 거리로 인한 전파 지연 |
| 유선 구간 | best-effort Ethernet | TSN 결합 | 산업 제어 deadline |

> 요약: 촉각 인터넷은 네트워크와 제어기가 가까울수록 유리하며, Edge 배치가 핵심 선택 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 지연 초과 | 무선 혼잡·코어 우회 | URLLC slice, MEC 배치 | RTT p99.999 |
| 제어 불안정 | jitter·패킷 손실 | 예측 제어, jitter buffer 최소화 | oscillation event |
| 안전 사고 | 원격 명령 지연·오류 | local fallback, emergency stop | fail-safe activation |

> 요약: 리스크는 지연 초과, 제어 불안정, 안전 사고이며 RTT 꼬리값과 안전 전환 로그로 검증한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연 | RTT 1ms~10ms 요구 범위 | hardware timestamp |
| 신뢰도 | packet loss 10^-5 이하 목표 | active probe |
| 안전 제어 | timeout 시 local stop 100% | fault injection |

> 요약: 촉각 인터넷 품질은 평균 지연이 아니라 RTT 꼬리값, 손실률, 안전 전환 성공률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 애플리케이션별 지연 예산을 단말 처리, 무선 접속, 전송망, Edge 처리, 피드백 구간으로 분해함.
2. URLLC slice, MEC 배치, TSN 802.1Qbv 유선 구간을 결합하고 hardware timestamp로 E2E 지연을 측정함.
3. 지연 초과와 패킷 손실 상황에서 local fallback, emergency stop, 제어 모드 전환을 fault injection으로 검증함.

**결론 (2줄):**
- 기술사 판단: 촉각 인터넷은 1ms 홍보 수치보다 전체 RTT 예산과 fail-safe 설계를 충족할 때 적용 가능함.
- 향후 방향: 5G-Advanced, 6G, Edge AI, TSN 연계로 원격 로봇과 산업 제어의 폐루프 네트워크가 구체화됨.
