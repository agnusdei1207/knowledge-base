## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 물리/가상 네트워크 자원 및 서비스 생명주기를 통합 자동화하는 오픈소스 오케스트레이터임 |
| 배경 | 통신사 벤더 종속성을 탈피하고 SDN/NFV 기반 가상화 망 관리를 단일 플랫폼으로 표준화 필요 |
| 출제 | 설계/실행 프레임워크 구조, 폐쇄 루프(Closed Loop) 자동화 제어, VNF 생명주기 |

## Ⅱ. 구성요소
```text
+--------------+        +--------------+        +--------------+
| Design Time  | -----> | Run Time Env | <----> | ONAP Portal  |
| (SDC)        | Model  | (SO, DCAE)   | Mgmt   | (Dashboard)  |
+--------------+        +--------------+        +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 설계 프레임워크 | 네트워크 서비스 및 리소스 모델을 설계하고 온보딩 카탈로그화함 | 설계 도면실 |
| 실행 프레임워크 | 네트워크 배포(SO) 및 수집된 텔레메트리 모니터링(DCAE) 수행함 | 공장 생산라인 |
| 통합 포털 | 관리자가 직관적으로 전체 네트워크 상태 제어 가능한 대시보드임 | 종합 관제실 |

> 요약: 네트워크 서비스를 사전 설계하고 이를 기반으로 실행 배포 및 모니터링 제어함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Design | -> | 2. Deploy | -> | 3. Monitor| -> | 4. Loop   |
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 템플릿 설계: SDC 환경에서 VNF 자원을 조립하여 네트워크 서비스 템플릿 작성함.
2. 자동 배포: SO 컴포넌트가 클라우드 인프라에 생성 명령을 내려 가상 망 배포함.
3. 성능 모니터링: DCAE가 배포된 네트워크망에서 실시간 텔레메트리 및 로그 수집함.
4. 폐쇄 루프 제어: 이상 탐지 시 정책 엔진 기반으로 자율 스케일링 등 복구 루프 실행함.

> 요약: 가상망을 설계 및 배포한 후, 실시간 감시를 통해 장애 발생 시 자율 복구함.

## Ⅳ. 문제점
- 플랫폼 비대: 수많은 마이크로서비스 구조로 인해 플랫폼 자체 K8s 구동 리소스 소모 극심함.
- 배포 난이도: 전체 아키텍처가 방대하여 통신사 환경 커스터마이징 및 초기 온보딩 난이도 높음.
- 레거시 호환: 구형 PNF 장비 및 이기종 멀티 벤더 솔루션 연동 시 표준 API 충돌 발생함.

## Ⅴ. 개선방안
- 경량화 패키지 (단기): 필수 핵심 모듈만 선택적으로 배포하는 Lightweight ONAP 모델 적용함.
- CNF 고도화 (중기): 가상머신 기반 VNF 대신 클라우드 네이티브 K8s(CNF) 최적화 관리를 우선함.
- 표준 API 확대 (장기): 개방형 벤더 생태계를 주도하여 장비 연동 제어 인터페이스를 완전 표준화함.

## Ⅵ. 전망
- ONAP는 통신사 5G 슬라이싱 통합 관리뿐만 아니라 자율 주행 네트워크 통합 두뇌로 자리잡을 것임.
