## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 서버 프로비저닝 없이 API 요청 및 이벤트에 따라 네트워크 리소스를 동적 할당하는 구조임 |
| 배경 | 트래픽 예측이 어려운 워크로드에서 인프라 관리 부담 해소 및 유연한 확장 필요 |
| 출제 | API 게이트웨이, 콜드 스타트, 상태 비저장 네트워크 제어 |

## Ⅱ. 구성요소
```text
+--------------+        +--------------+        +--------------+
| API Gateway  | -----> | Event Router | -----> | Compute Node |
| (Endpoint)   | Route  | (Event Bus)  | Exec   | (Lambda/FaaS)|
+--------------+        +--------------+        +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| API 게이트웨이 | 외부 HTTP 요청 수신, 인증 및 트래픽 스로틀링 수행함 | 통합 접수창구 |
| 이벤트 라우터 | 발생한 이벤트를 적절한 대상 서버리스 함수로 전달함 | 우편 집중국 |
| 컴퓨트 노드 | 네트워크 요청에 따라 일시적으로 실행되는 컨테이너임 | 임시 작업자 |

> 요약: 외부 요청과 이벤트를 수신하여 동적 컴퓨팅 자원으로 즉시 라우팅함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Trigger| -> | 2. ENI Req| -> | 3. Execute| -> | 4. Release|
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 이벤트 트리거: API 요청 또는 메시지 큐 등으로부터 이벤트 발생함.
2. 네트워크 할당: 서버리스 함수 실행을 위한 동적 네트워크 인터페이스(ENI) 할당함.
3. 함수 실행: 할당된 네트워크를 통해 사용자 코드가 백엔드 통신 및 연산 수행함.
4. 자원 해제: 응답 반환 후 일정 대기시간 초과 시 네트워크 연결 해제함.

> 요약: 이벤트 발생 시 네트워크 인터페이스를 동적 할당하여 코드 실행 후 해제함.

## Ⅳ. 문제점
- 콜드 스타트: 초기 네트워크(VPC/ENI) 환경 할당 시 심각한 지연 시간 발생함.
- 상태 유지 한계: 서버리스 특성상 장기적인 TCP/WebSocket 세션 유지가 어려움.
- 보안 가시성: 동적 IP 할당으로 인해 고정된 방화벽 정책 적용 및 추적 까다로움.

## Ⅴ. 개선방안
- 사전 할당 (단기): 프로비저닝된 동시성 기능을 통해 네트워크 지연 사전 방지함.
- 세션 외부화 (중기): Redis 등 외부 인메모리 스토어를 통해 상태 데이터 지속 유지함.
- 동적 보안 (장기): IP 대신 아이덴티티 및 제로 트러스트 기반 동적 보안 정책 적용함.

## Ⅵ. 전망
- 서버리스 네트워크는 엣지 컴퓨팅과 결합하여 초저지연 CDN 기반 엣지 함수로 진화할 것임.
