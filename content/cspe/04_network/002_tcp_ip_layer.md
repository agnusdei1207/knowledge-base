## Ⅰ. 개요
- **정의**: 인터넷의 기본 통신 프로토콜로, OSI 모델을 간소화한 4계층 구조의 실질적 표준(De facto)임.
- **배경 및 필요성**: 미 국방성의 ARPANET 프로젝트에서 이기종 네트워크 간의 신뢰성 있는 연결 요구.
- **출제 의도**: 실제 인터넷 환경을 구동하는 핵심 프로토콜 스택과 계층별 매핑 관계 이해도 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **응용 계층 (L4)** | 사용자 애플리케이션 서비스 제공 (HTTP, FTP, DNS 등) | 편지의 목적과 내용 |
| **전송 계층 (L3)** | 호스트 간 신뢰성 있는 데이터 전송 (TCP) 및 빠른 전송 (UDP) | 우편물의 등기/일반 분류 |
| **인터넷 계층 (L2)** | 패킷 라우팅 및 논리적 주소 지정 수행 (IP, ICMP, ARP) | 경유할 우체국 경로 설정 |

> 요약: TCP/IP 모델은 응용, 전송, 인터넷, 네트워크 인터페이스의 4계층으로 구성된 실용적 표준임.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **메시지 생성**: 응용 계층에서 사용자 데이터를 메시지 형태로 전송 계층에 전달함.
2. **세그먼트화**: 전송 계층(TCP)에서 데이터를 분할하고 포트 번호를 포함한 헤더를 추가함.
3. **패킷화 및 프레이밍**: 인터넷 계층(IP)에서 라우팅 정보를, 링크 계층에서 MAC 주소를 추가함.
4. **물리 전송 및 수신**: 네트워크 인터페이스 계층을 통해 전기 신호로 전송 후 수신 측에서 역캡슐화함.

> 요약: 데이터는 TCP/IP 각 계층을 거치며 세그먼트, 패킷, 프레임 형태로 변환되어 전송됨.

## Ⅳ. 문제점
- 계층 간 의존성 문제 (원인: 각 계층이 밀접하게 결합되어 있어 단일 계층만 교체하기 어려움)
- 보안 기능의 부재 (원인: 초기 설계 시 개방성을 중시하여 암호화/인증 기능이 결여됨)
- 주소 자원 고갈 (원인: IPv4 체계의 구조적 한계로 폭발적인 인터넷 기기 증가를 수용 불가)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 계층 독립성 강화 (API 및 소켓 인터페이스를 표준화하여 의존성 완화)
- **중기 방안**: [중기] 보안 프로토콜 연동 (IPsec, TLS 등을 각 계층에 추가 적용하여 통신 기밀성 확보)
- **장기 방안**: [장기] IPv6 기반 스택으로 전면 전환 (충분한 주소 공간과 내장형 보안을 제공하는 차세대 스택 도입)

## Ⅵ. 전망
- TCP/IP는 IoT 및 6G 시대에도 핵심 통신망으로 쓰이되, 보안과 QoS가 강화된 형태로 진화할 것임.
