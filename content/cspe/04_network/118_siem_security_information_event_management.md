## 미리 알고가기

- 로그 정규화는 서로 다른 장비 로그를 같은 형식으로 맞추는 절차임
- 상관분석은 여러 로그를 연결해 하나의 공격 징후로 보는 분석임
- 보안 관제는 이상 징후를 모니터링하고 대응으로 넘기는 운영 활동임
- 평균 탐지 시간은 이벤트가 발생한 뒤 탐지될 때까지 걸린 평균 시간임

## Ⅰ. 개요

- **정의/개념**: SIEM은 시스템과 네트워크와 보안 장비와 클라우드 로그를 수집하고 정규화하고 상관분석해 위협 징후를 탐지하는 통합 관제 플랫폼임
- **배경/필요성**: 공격은 여러 장비를 가로질러 움직이는데 로그가 제각각 흩어져 있으면 흐름을 놓치기 쉬우므로, 이벤트를 한곳에서 묶어 보는 분석 체계가 필요함

## Ⅱ. 특징

- 서로 다른 출처의 로그를 한 화면과 한 규칙 체계로 다룰 수 있음
- 사용자, 자산, 출발지, 시간 필드로 여러 장비의 이벤트를 하나의 공격 흐름으로 연결함
- 로그 양이 많아질수록 수집 범위보다 규칙 품질과 저장 비용 관리가 중요해짐
- 오탐 경보가 누적되면 분석 대기열이 증가해 실제 침해 경보의 확인이 지연됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 로그 관리 시스템 | SIEM |
|:---|:---|:---|
| 주된 역할 | 로그 저장과 조회가 중심임 | 탐지와 상관분석과 경보가 중심임 |
| 분석 방식 | 개별 로그 검색과 통계 | 규칙 기반 이벤트 상관분석 |
| 활용 목적 | 장애 확인과 감사 기록에 적합함 | 침해 탐지와 보안 관제에 적합함 |
| 운영 포인트 | 수집 보존 정책이 중요함 | 탐지 규칙과 경보 품질이 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 로그 수집기 | 서버와 장비와 클라우드 이벤트를 모음 |
| 정규화 엔진 | 다른 형식의 로그를 공통 필드로 맞춤 |
| 상관분석 규칙 | 여러 이벤트를 연결해 경보를 생성함 |
| 저장·검색 계층 | 장기 보관과 조사 검색을 지원함 |
| 관제 대시보드 | 경보와 추세와 조사 화면을 제공함 |

```text
+----------+    수집    +-------------+    분석    +-------------+    경보    +---------+
| 로그 원천   | ------> | 정규화 엔진    | ------> | 상관분석 규칙 | ------> | 관제 화면 |
+----------+          +-------------+          +-------------+          +---------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[로그 수집] -> [정규화] -> [상관분석] -> [경보 생성] -> [조사]
```

1. **로그 수집**: 다양한 원천에서 이벤트를 받아옴
2. **정규화**: 시간과 사용자와 자산 필드를 공통 형식으로 맞춤
3. **상관분석**: 관련 이벤트를 하나의 공격 징후로 묶음
4. **경보 생성**: 규칙과 임계값을 넘는 경우 경보를 올림
5. **조사**: 분석가가 맥락을 확인하고 대응 절차로 넘김

## Ⅵ. 실무 적용 및 유의점

1. SIEM은 여러 보안 장비를 묶어 가시성을 높여 주지만 무작정 로그를 다 넣으면 잡음만 늘어나므로 우선순위 자산과 탐지 시나리오를 먼저 정하고 경보 정확도와 평균 탐지 시간과 미분석 경보 적체를 같이 확인함
2. 장기 보관이 필요한 환경은 저장 비용이 빠르게 커지므로 보존 기간과 원본 로그 범위를 구분해 운영하고 검색 응답 시간과 저장 용량 증가율을 계속 봐야 함

## Ⅶ. 결론

SIEM은 여러 원천의 이벤트를 공통 필드로 연결해 단일 로그에서 확인하기 어려운 공격 흐름을 탐지함.
