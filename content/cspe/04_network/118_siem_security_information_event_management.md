# 📖 【암기용】 개념 완전 이해

> 목적: SIEM을 여러 보안 장비 로그를 모아 상관분석과 관제 증적을 만드는 플랫폼으로 이해하게 만든다.

## 한눈에
- **개요**: SIEM은 시스템, 네트워크, 보안 장비, 클라우드 로그를 수집·정규화·상관분석해 위협을 탐지하는 관제 플랫폼이다.
- **왜 필요한가**: 공격자는 VPN, AD, EDR, WAF, DB를 순차적으로 건드리므로 단일 장비 로그만 보면 전체 공격 흐름을 놓친다.
- **핵심 직관**: CCTV, 출입기록, 카드사용 내역을 한곳에서 시간순으로 맞춰 사건을 재구성하는 관제실이다.

## 깊이 이해
- **배경·문제의식**: 보안 장비가 늘수록 로그 형식이 달라지고, 공격 징후는 여러 시스템에 작은 흔적으로 흩어진다.
- **작동 원리**: SIEM은 Syslog, Agent, API로 로그를 수집하고, 공통 필드로 정규화한 뒤 룰, 임계치, UEBA, Threat Intelligence로 상관분석한다.
- **비유**: 여러 부서의 사건 보고서를 같은 양식으로 바꾼 뒤 시간, 사람, 장소를 기준으로 연결해 사건 파일을 만드는 절차와 같다.
- **구체 예시**: VPN 해외 로그인, AD 실패 로그인 20회, EDR 악성 실행, DB 대량 조회가 30분 안에 연결되면 계정 탈취 후 내부 침해 시나리오로 경보를 낸다.
- **흔한 오해·주의점**: SIEM은 로그 저장소가 아니다. 탐지 룰 품질, 정규화, 티켓 처리, 오탐 튜닝이 없으면 저장 비용만 늘어난다.

## 연결 개념
- SOAR - SIEM 경보를 받아 대응 절차를 자동화
- EDR/NDR - 엔드포인트와 네트워크 탐지 이벤트를 SIEM에 제공
- UEBA - 사용자·엔터티 행위 기준 이상 징후 탐지

# 📝 【답안용】 시험 답안 템플릿

> 목적: SIEM 답안은 로그 수집, 정규화, 상관분석, 경보, 대응 연계, 지표를 단계별로 작성한다.
> 핵심: 공격·통제·증적·지표를 분리하고, MTTD와 오탐률을 운영 품질 지표로 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIEM은 이기종 로그를 통합해 상관분석 룰과 위협 인텔리전스로 보안 이벤트를 탐지하는 관제 플랫폼이다.
> 2. **가치**: 단일 장비가 놓친 공격 흐름을 사용자, IP, 자산, 시간 축으로 연결해 MTTD를 줄인다.
> 3. **판단 포인트**: 로그 소스 커버리지, 정규화 품질, 룰 정확도, 경보 처리 프로세스, 보존 정책을 함께 평가한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 관제 구조 이해 확인 | 수집, 정규화, correlation, alert, ticket | 로그 저장만 설명 |
| 탐지 품질 판단 확인 | MITRE ATT&CK, UEBA, TI, 오탐 튜닝 | 룰 개수만 많으면 된다고 작성 |
| 운영 지표 제시 확인 | MTTD, MTTR, EPS, 로그 보존, 오탐률 | 증적과 지표 누락 |

> 요약: SIEM 문제는 로그를 모으는 기술보다 공격 흐름을 탐지 가능한 증적으로 바꾸는 능력을 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 로그 상관분석 관제 플랫폼
- 배경: 공격 징후가 방화벽, VPN, AD, EDR, 클라우드 로그에 분산됨.
- 필요성: SIEM correlation으로 계정 탈취, 내부 이동, 데이터 반출을 시간순으로 탐지해야 함.
- 판단 기준: EPS, 로그 보존 기간, 탐지 룰 품질, 관제 인력 처리량을 기준으로 설계함.

---

## Ⅱ. 구조 및 구성요소

```text
Log Sources -> Collector -> Parser/Normalizer -> SIEM Data Lake
            -> Correlation/UEBA/TI -> Alert -> Ticket/SOAR
            +-> Dashboard/Report -> Audit Evidence
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Log Source | 방화벽, VPN, AD, EDR, WAF, CloudTrail 이벤트 제공 | 중요 자산 우선순위 필요 |
| Collector | Syslog, Agent, API로 로그 수집 | EPS, 버퍼링, 전송 암호화 |
| Parser/Normalizer | 벤더별 필드를 공통 스키마로 변환 | 사용자 ID, IP, 자산 ID 정합성 |
| Correlation Engine | 다중 이벤트를 룰·시간창 기준으로 연결 | MITRE ATT&CK 매핑 |
| Dashboard/Report | 경보 현황과 감사 증적 제공 | 보존 기간, 검색 성능, 접근권한 |

> 요약: SIEM은 로그 소스에서 수집한 이벤트를 정규화하고 상관분석해 경보와 감사 증적을 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그 발생 -> 수집/버퍼링 -> 파싱/정규화 -> 저장/색인
-> 상관분석 -> 경보 생성 -> 티켓/대응 -> 룰 튜닝
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 보안 장비와 클라우드 로그를 수집 | EPS, 누락률, 수집 지연 |
| 2 | 필드를 공통 스키마로 정규화 | src_ip, user, asset, event_type |
| 3 | 룰과 UEBA가 이벤트를 상관분석 | 시간창, 임계치, TI 매칭 |
| 4 | 경보를 관제 티켓으로 생성 | 우선순위, 자산 중요도, 담당자 |
| 5 | 처리 결과로 룰을 튜닝 | 오탐률, 재발 경보, 룰 변경 이력 |

> 요약: SIEM은 로그를 이벤트로 바꾸고, 이벤트를 공격 시나리오로 연결하며, 처리 결과로 탐지 룰을 개선한다.

## Ⅳ. 특징

| 구분 | 개별 장비 로그 | SIEM 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 가시성 | 장비별 화면 분산 | 사용자·자산·시간 축 통합 | 공통 스키마, CMDB 연계 |
| 탐지 방식 | 단일 이벤트 탐지 | correlation, UEBA, TI | MITRE ATT&CK TTP |
| 운영 증적 | 장비별 보존 | 중앙 보존과 감사 리포트 | 1년 이상 보존 정책 |
| 한계 | 오탐 판단 어려움 | 룰 품질과 로그 비용 관리 필요 | EPS, storage, false positive |

> 요약: SIEM은 이기종 로그를 공격 시나리오로 연결하지만, 정규화와 룰 튜닝 없이는 경보 품질이 낮아진다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 전통 SIEM | 차세대 SIEM/융합 관제 | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 | Syslog 중심 | Cloud, EDR, NDR, SaaS API | 클라우드·SaaS 사용 비중 |
| 분석 | 룰 기반 correlation | UEBA, ML, TI, ATT&CK | 오탐률과 탐지 공백 |
| 대응 | 관제원이 수동 처리 | SOAR 티켓·playbook 연계 | 반복 경보 비율 |
| 비용 | 저장 용량 중심 | 데이터 티어링, 검색 최적화 | EPS와 보존 기간 |

> 요약: 클라우드와 엔드포인트 로그 비중이 높으면 차세대 SIEM과 SOAR 연계를 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 로그 누락 | 소스 미등록, 파서 실패 | 중요 자산 로그 커버리지 관리 | 수집 누락률, 파서 오류 |
| 오탐 과다 | 임계치 부적절, 자산 맥락 부족 | CMDB 연계, 룰 튜닝 | false positive rate |
| 탐지 지연 | 수집 지연, 검색 병목 | Collector 확장, 인덱스 최적화 | end-to-end delay |
| 비용 증가 | EPS 증가와 장기 보존 | 로그 티어링, 중요도별 보존 | GB/day, 저장 비용 |

> 요약: SIEM 리스크는 로그 품질, 오탐, 탐지 지연, 저장 비용을 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 로그 커버리지 | 중요 자산 95% 이상 수집 | CMDB와 로그 소스 대조 |
| 탐지 시간 | MTTD 10분 이하 | 경보 생성 시간 분석 |
| 오탐률 | 고위험 룰 오탐 20% 이하 | 티켓 종결 사유 분석 |
| 보존 정책 | 규정 요구 기간 충족 | 저장소 정책, 감사 리포트 |

> 요약: SIEM 운영 성과는 로그 커버리지, MTTD, 오탐률, 보존 정책 준수로 평가한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 방화벽, VPN, AD, EDR, WAF, CloudTrail을 우선 로그 소스로 등록하고 사용자 ID와 자산 ID를 공통 필드로 정규화함.
2. MITRE ATT&CK 기준으로 계정 탈취, 내부 이동, 데이터 반출 correlation 룰을 만들고 룰별 MTTD와 오탐률을 관리함.
3. 고위험 경보는 SOAR 티켓과 playbook으로 연결하고, 반복 오탐은 주간 튜닝 회의에서 임계치와 예외 조건을 조정함.

**결론 (2줄):**
- 기술사 판단: SIEM은 로그 저장소가 아니라 공격 흐름을 탐지하고 증적화하는 관제 플랫폼으로 설계해야 함.
- 향후 방향: SIEM은 XDR, UEBA, SOAR와 결합해 데이터 기반 융합 보안 관제 체계로 발전함.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "SIEM을 설명하시오" | 로그 수집부터 correlation까지 흐름 | 로그 통합과 탐지 방식 |
| 요구사항 명시형 | "보안 관제 구축 방안을 제시하시오" | 소스 등록, 룰 설계, 티켓 처리 | MTTD, 오탐률, 보존 정책 |

> 요약: 설명형은 SIEM 구조를, 방안형은 관제 프로세스와 운영 지표를 중심으로 쓴다.
