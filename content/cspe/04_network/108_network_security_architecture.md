## Ⅰ. 개요
- **정의**: 네트워크 계층별 보안 기능을 체계적으로 배치하여 위협을 탐지·차단·대응하는 설계 체계임
- **배경/필요성**: 공격 벡터가 다층화되면서 단일 장비 기반 방어로는 탐지 우회와 내부 확산을 차단하기 어려움
- **비유**: 성벽(경계)·검문소(구간)·순찰대(내부)를 다층 배치하는 성곽 방어 체계와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 심층 방어(Defense in Depth) 원칙과 구성 | 경계·내부·종단 보안 3계층, NGFW·IPS·NDR | 제로트러스트(109 참조)와 경계 기반 보안의 차이 구분 |

> 요약: 경계-내부-종단 다층 보안 기능을 체계적으로 배치하는 네트워크 방어 설계임

## Ⅱ. 구성요소
```text
[Internet]
     |
+----+-----+
| 경계 보안 |  <-- NGFW, WAF, Anti-DDoS
+----+-----+
     |
+----+------+
| 내부 보안  |  <-- IPS, NDR, 세그멘테이션
+----+------+
     |
+----+------+
| 종단 보안  |  <-- EDR, NAC, Host FW
+-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 경계 보안 | NGFW·WAF·DDoS 방어로 외부 진입점 차단 | 성문 검문소 |
| 내부 보안 | IPS·NDR·마이크로세그멘테이션으로 내부 확산 방지 | 내부 순찰대 |
| 종단 보안 | EDR·NAC·호스트 방화벽으로 엔드포인트 보호 | 개인 경호원 |

> 요약: 경계·내부·종단 3계층에 보안 기능을 배치하여 심층 방어를 구현함

## Ⅲ. 절차
```text
위협분석 --> 보안구역설계 --> 보안장비배치 --> 모니터링/대응
```
- 1단계: 자산 식별 및 위협 모델링으로 보호 대상과 공격 경로 분석
- 2단계: 네트워크를 보안 구역(Zone)으로 분리하고 구역 간 정책 정의
- 3단계: 각 구역 경계에 NGFW·IPS·NDR 등 보안 장비를 인라인/미러 배치
- 4단계: SIEM·SOAR 연동으로 이벤트 통합 모니터링 및 자동 대응 체계 구축

> 요약: 위협 분석, 구역 설계, 장비 배치, 통합 모니터링 순으로 보안 아키텍처를 수립함

## Ⅳ. 문제점
- 암호화 트래픽 사각지대: TLS 1.3 확산으로 인라인 복호화 없이 내용 검사가 불가함
- 보안 장비 간 사일로: 벤더별 로그 형식 상이로 통합 상관분석이 지연됨
- 성능 병목: 인라인 보안 장비 체인이 길어지면 지연 증가 및 단일 장애점 발생

> 요약: 암호화 사각지대, 장비 간 사일로, 인라인 성능 병목이 주요 과제임

## Ⅴ. 개선방안
1. 단기: TLS 복호화 전용 장비(SSL Orchestrator) 도입으로 암호화 가시성 확보
2. 중기: XDR/SIEM 통합 플랫폼으로 멀티벤더 로그 정규화 및 상관분석 자동화
3. 장기: 서비스 체이닝·NFV 기반 동적 보안 기능 삽입으로 성능과 유연성 확보

> 요약: SSL 오케스트레이션, XDR 통합, NFV 서비스 체이닝으로 단계적 개선 필요

## Ⅵ. 전망
- 발전 방향: SASE·SSE 프레임워크로 네트워크 보안 기능이 클라우드 에지로 이동하는 추세임
- 기술사적 판단: 제로트러스트(109 참조) 원칙이 경계 중심 보안을 대체하는 전환점에 있음
- 기술사 제언: 경계 보안과 제로트러스트의 공존 전략을 수립하고 단계적 전환 로드맵이 필요함
