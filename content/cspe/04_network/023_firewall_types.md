# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 방화벽(Firewall)은 네트워크 경계에서 보안 정책(Rule-set)에 따라 트래픽의 **허용(Allow)·차단(Deny)**을 결정하는 **접근 통제 시스템**이며, 검사 깊이에 따라 패킷 필터(1세대)→상태 기반(2세대)→NGFW(3세대)로 진화함.
- **왜 필요한가**: 외부 네트워크(인터넷)로부터 내부 자산을 보호하는 1차 방어선이며, 포트 우회 공격·암호화 악용 등 위협이 고도화되면서 단순 IP/포트 차단을 넘어선 심층 검사가 필수가 됨.
- **핵심 직관**: 1세대는 신분증(IP/Port)만 확인하는 경비원, 2세대는 방문 예약 기록(세션 상태)을 대조하는 경비원, 3세대(NGFW)는 가방 속을 X-ray(DPI)로 검사하는 공항 보안 검색대.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 접근 통제 (상위 키워드) | 주체(사용자·시스템)가 객체(자원)에 접근할 때 인가 여부를 판단하는 보안 메커니즘 | 건물 출입 카드 시스템 |
| ACL (Access Control List) | IP·Port·Protocol을 기준으로 허용/차단을 정의한 규칙 목록 | 출입 허가자 명단 |
| SPI (Stateful Packet Inspection) | TCP 세션 상태 테이블을 유지하여 연결 문맥을 추적하는 검사 방식 | 내가 주문한 택배인지 배송 기록으로 확인 |
| State Table | SPI 방화벽이 유지하는 활성 세션(5-tuple + 상태) 목록 | 방문 예약 대장 |
| DPI (Deep Packet Inspection) | 패킷 Payload까지 분석하여 애플리케이션·악성코드를 식별하는 기술 | X-ray로 내용물 검사 |
| App-ID | NGFW가 포트와 무관하게 애플리케이션을 식별하는 기능(예: YouTube, Slack) | 택배 내용물의 브랜드 확인 |
| User-ID | NGFW가 IP가 아닌 사용자 계정(AD 연동)으로 정책을 적용하는 기능 | 경비원이 이름으로 출입 관리 |
| SSL Inspection | 암호화(TLS) 트래픽을 MITM 방식으로 복호화하여 검사하는 기능 | 봉인된 상자를 열어 검사 후 재봉인 |
| NGFW (Next-Gen Firewall) | SPI + DPI + App-ID + IPS + SSL Inspection을 통합한 3세대 방화벽 | 출입·검사·CCTV가 통합된 보안 센터 |

## 깊이 이해
- **배경·문제의식**: 1세대 패킷 필터는 IP/Port만 보고 허용했으나, TCP Flag 조작·IP 스푸핑으로 쉽게 우회됨. 2세대 SPI가 세션 상태를 추적하여 비정상 패킷을 차단했으나, 포트 80/443으로 들어오는 웹 애플리케이션 공격(SQLi·XSS)은 정상 세션으로 인식되어 통과함. 3세대 NGFW가 Payload까지 분석하여 L7 공격을 탐지·차단하게 됨.
- **1세대 — 패킷 필터링(Stateless)**: 각 패킷을 독립적으로 ACL과 대조함. 이전 패킷과의 관계(세션)를 모르므로, 응답 패킷을 허용하려면 별도 규칙을 추가해야 하고, 이 과정에서 허용 범위가 넓어져 보안 허점이 생김.
- **2세대 — 상태 기반 검사(SPI, Stateful)**: 내부에서 외부로 TCP 3-way Handshake를 시작하면 State Table에 세션을 등록하고, 해당 세션의 응답 패킷은 테이블을 보고 자동 허용함. 별도 응답 규칙이 불필요하므로 ACL이 간결해지고, 비정상 패킷(SYN 없이 ACK만 보내는 등)을 상태 불일치로 탐지·차단함.
- **3세대 — NGFW**: SPI 위에 DPI·App-ID·User-ID·IPS·Sandbox·SSL Inspection을 통합함. 포트 80을 쓰는 YouTube와 악성 C&C를 구분하고(App-ID), IP가 아닌 사용자 계정 단위로 정책을 적용하며(User-ID), 암호화 트래픽도 복호화하여 은닉 위협을 검사함.
- **비유**: 1세대는 송장만 보고 통과시키는 택배 기사. 2세대는 "내가 주문한 건지" 배송 기록을 확인하는 수령인. 3세대는 상자를 열어 내용물이 위험물인지 성분 분석까지 하는 세관 검사관.
- **구체 예시**: 2세대 방화벽은 포트 443(HTTPS)이 허용되면 SSL로 암호화된 악성 C&C 통신도 정상으로 통과시킴. NGFW는 SSL Inspection으로 트래픽을 복호화한 뒤 App-ID로 C&C 패턴을 식별하여 차단함.
- **흔한 오해·주의점**: "NGFW면 모든 보안 문제가 해결된다"는 오해가 흔함. NGFW는 DPI·SSL 복호화로 CPU 부하가 크므로, 대용량 트래픽 구간에서는 앞단에 HW 패킷 필터로 볼류메트릭 DDoS를 걸러내고 NGFW는 정밀 검사에 집중하는 계층 방어가 필수임. 또한 웹 애플리케이션 로직 취약점(OWASP Top 10)은 전용 WAF(116)가 더 정밀하게 대응함.

## 연결 개념
- **IDS·IPS(024)**: NGFW에 통합되는 침입 탐지·차단 기능, 독립 장비로도 운영됨.
- **WAF(116)**: 웹 서비스 전용 L7 방화벽, NGFW 후단에 배치되는 2-Tier 구성.
- **SASE(114)**: 방화벽 기능이 클라우드 엣지 서비스(FWaaS)로 편입되는 최신 아키텍처.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 방화벽은 네트워크 경계에서 헤더(1세대)→세션 상태(2세대)→애플리케이션 Payload(3세대)를 기준으로 트래픽을 필터링하는 접근 통제 시스템임.
> 2. **가치**: NGFW는 DPI·App-ID·SSL Inspection 통합으로 포트 우회 공격·암호화 은닉 위협까지 방어 범위를 확장함.
> 3. **판단 포인트**: 검사 깊이 증가는 처리 지연과 직결되므로, 볼류메트릭 방어(앞단 패킷 필터)와 정밀 검사(NGFW)의 계층 배치가 핵심 설계 포인트임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세대별 방화벽 진화 원리 | Stateless→Stateful→DPI/App-ID 전환 논리, 각 세대의 한계 | 세대별 정의만 나열, 한계→극복 인과관계 누락 |
| NGFW 차별점 | App-ID·User-ID·SSL Inspection·IPS 통합 | "보안이 강화된다" 식 추상 표현 |
| 성능 트레이드오프 설계 | SSL 복호화 시 Throughput 저하, NPU 오프로딩 | NGFW 만능론, 대용량 구간 병목 간과 |

> 요약: 세대별 "무엇을 검사하는가"의 진화와, NGFW의 성능-보안 트레이드오프 해결 방안을 서술해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 네트워크 경계에서 보안 정책(Rule-set)에 따라 트래픽 통과 여부를 통제하는 접근 통제 시스템임.
- 배경: 포트 기반 통제(L4)를 우회하는 웹 애플리케이션 공격(L7)과 암호화 트래픽 악용 위협이 급증함.
- 필요성: IP/Port 차단을 넘어 애플리케이션 식별(App-ID), 암호화 트래픽 검사(SSL Inspection), 사용자 기반 정책(User-ID)을 통합하는 NGFW가 필수임.

---

## Ⅱ. 구조 및 구성요소

```text
[1세대 패킷 필터] -> [2세대 상태 기반(SPI)] -> [3세대 NGFW]
IP/Port ACL 대조     Session Table 추적         App-ID + DPI + IPS + SSL Inspection
(Stateless)          (Stateful, Context)        (Content Aware, User Aware)
```

| 구성요소 | 핵심 메커니즘 | 통제 기준 |
|:---|:---|:---|
| 패킷 필터(1세대) | ACL 기반 개별 패킷 대조(Stateless) | L3/L4 헤더(IP·Port·Protocol) |
| 상태 기반(2세대) | State Table 유지, 세션 문맥 추적(Stateful) | TCP 연결 상태(SYN→ESTABLISHED) |
| NGFW(3세대) | DPI + App-ID + User-ID + IPS + SSL Inspection | L7 Payload, 애플리케이션, 사용자 계정 |

> 요약: 1세대는 패킷 헤더, 2세대는 세션 문맥, 3세대는 Payload 내용까지 검사 범위를 확장한 진화 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
패킷 수신 -> L3/L4 ACL 검사(Fast Path) -> Session Table 확인(SPI) -> SSL 복호화 -> App-ID/DPI 분석 -> IPS 시그니처 대조 -> 허용/차단 + 로그 기록
```

1. L3/L4 기본 필터링(Fast Path): 출발지·목적지 IP·Port를 ACL과 대조하여 명백한 차단 대상을 즉시 폐기함. 하드웨어 ASIC으로 와이어스피드 처리함.
2. 세션 상태 확인(SPI): State Table에 등록된 세션인지 확인하여, 내부 요청의 정상 응답은 자동 허용하고 비정상 패킷(SYN 없는 ACK 등)은 차단함.
3. SSL 복호화·App-ID 분석: NGFW가 TLS 트래픽을 MITM 방식으로 복호화한 뒤, Payload를 DPI로 분석하여 애플리케이션(YouTube·Slack·C&C)을 식별함.
4. IPS·최종 판정: 식별된 트래픽에 IPS 시그니처·Sandbox 분석을 적용하여 악성 여부를 판정하고, 정책에 따라 허용·차단·격리 후 로그를 기록함.

> 요약: NGFW는 L3/L4 고속 필터링 후 SSL 복호화→App-ID→IPS 순서로 심층 검사를 단계적으로 수행하여 성능과 보안을 균형 있게 처리함.

---

## Ⅳ. 특징

- 1세대 한계: 개별 패킷만 보므로(Stateless) TCP Flag 조작·IP 스푸핑에 취약하고, 응답 허용 규칙 추가로 ACL이 비대해짐.
- 2세대 개선: 세션 문맥 추적(Stateful)으로 ACL이 간결해지고 비정상 패킷을 탐지하나, 포트 80/443으로 들어오는 L7 공격(SQLi·XSS)은 정상 세션으로 통과시킴.
- 3세대 통합: DPI·App-ID·User-ID·IPS·SSL Inspection을 단일 플랫폼에 통합하여 L7 위협·암호화 은닉을 방어하나, CPU 부하가 크고 SSL 복호화 시 Throughput이 40~60% 저하됨.
- 계층 방어 필수: 대용량 구간에서 NGFW 단독 배치 시 병목이 발생하므로, 앞단에 HW 패킷 필터로 볼류메트릭 DDoS를 걸러내는 심층 방어(Defense in Depth) 구성이 필요함.

> 요약: 세대가 진화할수록 보안 가시성은 향상되나 처리 부하가 증가하므로, 구간별 계층 방어 설계가 핵심임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | NGFW (차세대 방화벽) | WAF (웹 방화벽, 116) | 선택 기준 |
|:---|:---|:---|:---|
| 보호 범위 | 네트워크 경계 전체 트래픽 | 웹 서버 전용(HTTP/HTTPS) | 인바운드 웹 서비스 여부 |
| 검사 깊이 | App-ID·User-ID·IPS | OWASP Top 10(SQLi·XSS·CSRF) | 웹 로직 취약점 정밀 방어 필요 |
| 배치 위치 | 인터넷 게이트웨이 경계 | 웹 서버 팜 직전(Reverse Proxy) | NGFW 후단에 WAF 배치가 표준 |

> 요약: 관문에는 NGFW, 웹 서비스 앞단에는 WAF를 배치하는 2-Tier 심층 방어가 표준 구성임.

**리스크·대응:**
- NGFW 성능 병목: SSL 복호화+DPI 시 Throughput 40~60% 저하 → 전용 NPU 가속기 탑재, Fast Path 바이패스 설정 (지표: SSL 활성화 시 Throughput 저하율)
- 세션 테이블 고갈: SYN Flood로 State Table 초과 → SYN Cookie 적용, CPS 제한 (지표: 세션 테이블 점유율 80% 경보)
- IPS 오탐(False Positive): 엄격한 시그니처 적용으로 정상 업무 차단 → 탐지 모드 검증 후 차단 전환, 예외 정책 세분화 (지표: False Positive 건수)

**점검 지표:**
- 성능: SSL 복호화 활성화 시 Throughput — 장비 스펙의 60% 이상 유지 목표
- 보안: App-ID 식별율 — 전체 트래픽의 95% 이상 애플리케이션 식별

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 심층 방어(Defense in Depth): 최외곽에 HW 패킷 필터(ACL)로 볼류메트릭 DDoS를 차단하고, 내부에 NGFW를 배치하여 App-ID·SSL Inspection 기반 정밀 검사를 수행함.
2. 마이크로 세그멘테이션: App-ID를 활용하여 "TCP 80 전체 허용"을 "YouTube 허용, 파일전송 차단" 수준으로 세분화하고, User-ID로 부서·직급별 차등 정책을 적용함.
3. 암호화 트래픽 검사: 사내 단말에 루트 인증서를 배포하고 NGFW에서 SSL Inspection을 활성화하여, HTTPS로 은닉된 C&C·악성 다운로드를 탐지·차단함.

**결론:**
- 기술사 판단: NGFW는 패킷 필터→SPI의 기능 확장이 아니라 컨텍스트 기반 통제(App·User·Content Aware)로의 패러다임 전환이며, SSL 복호화 성능이 장비 선정의 핵심 기준임.
- 향후 방향: SASE(114)·Zero Trust 아키텍처에서 방화벽 기능이 클라우드 엣지 서비스(FWaaS)로 편입되고, 네트워크 경계 중심 방어에서 모든 접근을 검증하는 ID 기반 통제로 전환되는 추세임.
