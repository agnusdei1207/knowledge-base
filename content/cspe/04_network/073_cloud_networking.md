## Ⅰ. 개요
- **정의**: 클라우드 환경에서 가상 네트워크를 소프트웨어로 정의·운영하는 기술임
- **배경/필요성**: 물리 네트워크는 프로비저닝에 수일 소요되므로 클라우드 워크로드의 탄력적 확장에 대응이 불가함
- **비유**: 물리 네트워크가 도로 공사라면, 클라우드 네트워킹은 내비게이션으로 경로를 즉시 변경하는 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 가상 네트워크 추상화 계층 이해 | Overlay/Underlay 분리 구조 | SDN과의 관계, VPC(074 참조)와의 구분 명시 필요 |

> 요약: 소프트웨어 정의 방식으로 클라우드 워크로드에 탄력적 네트워크를 제공하는 기술임

## Ⅱ. 구성요소
```text
Tenant App --> Virtual NIC --> Virtual Switch --> Overlay Network --> Underlay Fabric
                                    |                   |
                                 vSwitch            VXLAN/Geneve
                                (OVS/VPP)           Encapsulation
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Virtual Switch | 하이퍼바이저 내에서 VM/컨테이너 트래픽을 L2 스위칭함 | 건물 내부 배전반 |
| Overlay Network | VXLAN/Geneve 캡슐화로 물리 토폴로지와 독립된 가상 L2 세그먼트를 구성함 | 도로 위에 놓인 고가도로 |
| Underlay Fabric | 물리 스위치·라우터로 구성된 IP 전송 인프라임 | 실제 도로망 |

> 요약: Virtual Switch-Overlay-Underlay 3계층으로 가상 네트워크를 구현함

## Ⅲ. 절차
```text
Step1 Define --> Step2 Provision --> Step3 Connect --> Step4 Enforce
```
- 1단계: 테넌트가 API로 서브넷·라우팅·보안 규칙을 선언함
- 2단계: 컨트롤러가 가상 스위치·라우터에 설정을 자동 배포함
- 3단계: Overlay 터널을 통해 분산된 워크로드 간 L2/L3 연결을 수립함
- 4단계: 보안 그룹·ACL 정책을 가상 NIC 단위로 적용함

> 요약: 선언-배포-연결-정책적용 순서로 가상 네트워크를 구성함

## Ⅳ. 문제점
- Overlay 오버헤드: 캡슐화/역캡슐화로 패킷당 50바이트 헤더가 추가되어 유효 MTU가 감소함
- 가시성 부족: Overlay 내부 트래픽이 물리 장비에서 보이지 않아 장애 구간 식별이 어려움
- 멀티 클라우드 호환성: CSP별 가상 네트워크 구현 차이로 통합 관리가 복잡함

> 요약: 캡슐화 오버헤드, 가시성 부족, CSP 간 호환성이 핵심 과제임

## Ⅴ. 개선방안
1. 단기: Jumbo Frame(MTU 9000) 적용으로 캡슐화 오버헤드 비율을 최소화함
2. 중기: eBPF(079 참조) 기반 In-band 텔레메트리로 Overlay 내부 가시성을 확보함
3. 장기: 멀티 클라우드 네트워크 추상화 계층(076 참조) 도입으로 CSP 독립적 관리를 구현함

> 요약: MTU 확대, 내부 가시성, 추상화 계층으로 클라우드 네트워크를 고도화함

## Ⅵ. 전망
- 발전 방향: NaaS(Network as a Service) 모델로 네트워크 소비 방식이 전환됨
- 기술사적 판단: 컨테이너·서버리스 워크로드 증가에 따라 L7 수준 네트워킹 중요도가 상승함
- 기술사 제언: Overlay-Underlay 간 일관된 모니터링 체계 설계가 필요함
