## 미리 알고가기

- 거리 벡터: 목적지까지의 비용과 다음 홉 방향을 인접 라우터에게 받아 경로를 정하는 방식임
- RIP: 홉 수를 메트릭으로 쓰는 대표적인 거리 벡터 내부 라우팅 프로토콜임
- Path Vector: BGP처럼 AS 경로 목록을 포함해 루프와 정책을 판단하는 라우팅 방식임
- Count to Infinity: 잘못된 거리 정보가 단계적으로 증가하며 수렴이 지연되는 현상임

## Ⅰ. 개요

- **정의/개념**: 거리 벡터 라우팅은 인접 라우터가 알려 준 목적지까지의 거리와 다음 홉 정보를 바탕으로 라우팅 테이블을 갱신하는 방식임
- **배경/필요성**: 전체 토폴로지를 모두 알지 않아도 인접 장비와의 정보 교환만으로 경로를 만들 수 있어 단순한 내부망에서 쓰기 쉬움

## Ⅱ. 특징

- 라우터는 목적지별 거리와 다음 홉을 주기적으로 또는 변화 시 인접 라우터와 교환함
- RIP은 홉 수를 사용하므로 링크 대역폭이나 지연 차이를 경로 비용에 반영하지 못함
- 루프를 줄이기 위해 Split Horizon, Route Poisoning, Hold-down 같은 기법을 사용함
- BGP는 단순 거리 벡터가 아니라 AS 경로와 정책 속성을 쓰는 Path Vector로 구분해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | RIP | BGP |
|:---|:---|:---|
| 라우팅 범위 | 하나의 조직 내부 소규모망에 쓰는 IGP임 | AS 사이 인터넷 경로를 교환하는 EGP임 |
| 경로 정보 | 목적지와 홉 수를 중심으로 판단함 | AS_PATH, LOCAL_PREF, MED 등 속성을 판단함 |
| 루프 방지 | 거리 벡터 보완 기법으로 루프를 완화함 | AS_PATH에 자기 AS가 있으면 경로를 거부함 |
| 선택 기준 | 단순 구성과 제한된 규모가 전제임 | 정책, 계약, 트래픽 방향 제어가 전제임 |

> 요약: RIP은 거리 벡터 IGP이고, BGP는 AS 경로와 정책 속성을 쓰는 Path Vector EGP임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Distance | 목적지까지의 비용이며 RIP에서는 홉 수가 해당함 |
| Vector | 목적지로 가기 위해 선택한 다음 홉 방향임 |
| Routing Update | 인접 라우터에게 목적지별 거리 정보를 알리는 메시지임 |
| Loop Prevention | 잘못된 경로 정보가 반복 전파되지 않도록 제한하는 기법임 |

```text
+--------+   update: N=2 hops   +--------+   update   +--------+
|Router A| <------------------> |Router B| <--------> |Router C|
+--------+                      +--------+            +--------+
```

> 요약: 거리 벡터 구조는 인접 라우터의 거리 정보를 받아 자신의 다음 홉과 비용을 갱신함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 정보수신  | --> | 비용계산  | --> | 경로갱신  | --> | 이웃전파 |
+----------+     +----------+     +----------+     +----------+
```

1. **정보수신**: 라우터가 인접 라우터의 목적지별 거리 정보를 받음
2. **비용계산**: 이웃까지의 비용을 더해 자신의 후보 경로 비용을 계산함
3. **경로갱신**: 더 적합한 경로이면 라우팅 테이블의 다음 홉과 비용을 바꿈
4. **이웃전파**: 갱신된 정보를 다시 인접 라우터에게 알림

## Ⅵ. 실무 적용 및 유의점

1. RIP을 교육용이나 소규모 폐쇄망에 쓸 때도 홉 수 15 제한과 느린 수렴을 고려해야 하며 라우팅 루프 여부와 업데이트 주기로 확인함
2. BGP를 거리 벡터와 같은 방식으로 설명하면 정책 라우팅의 본질이 빠지므로 AS_PATH와 LOCAL_PREF 같은 속성을 기준으로 경로 선호와 차단 로그를 확인함

## Ⅶ. 결론

거리 벡터 라우팅은 이웃의 거리 정보를 따라 경로를 갱신하는 절차이며, BGP는 정책 속성을 쓰는 Path Vector로 따로 구분해야 함.

## 작성 근거(검토용)

- 제목에 RIP·BGP가 함께 있으나 BGP를 거리 벡터로 단정하면 부정확하므로 Path Vector 차이를 명시함
- 추상적인 장점 표현은 홉 수 제한, AS_PATH, LOCAL_PREF처럼 기술 판단 기준으로 바꿈
- 결론은 RIP과 BGP의 분류 혼동을 방지하기 위해 두 방식의 절차 차이를 회수함
