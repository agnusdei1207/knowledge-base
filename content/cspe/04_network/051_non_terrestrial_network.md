# 📖 【암기용】 개념 완전 이해

> 목적: NTN과 LEO 위성망을 처음 보는 사람도 지상 5G와 어떻게 연결되는지 이해하게 만든다. 시험 답안 양식이 아니라, 개념을 위한 설명이다.

## 한눈에
- **개요**: NTN은 위성·HAPS·UAV를 3GPP 이동통신망에 연결하는 비지상 무선 접속 구조다.
- **왜 필요한가**: 산악·해상·항공·재난 지역은 지상 기지국 설치가 제한된다. LEO 위성은 약 500~2,000km 고도에서 지구를 돌며 지상망 공백을 보완한다.
- **핵심 직관**: 기지국을 철탑에만 세우는 것이 아니라, 위성 궤도에 올려 단말과 5G 코어를 이어 주는 방식이다.

## 깊이 이해
- **배경·문제의식**: 5G 지상망은 기지국 반경·전원·백홀에 의존한다. 3GPP Release 17 NTN은 위성 채널의 긴 전파 지연, 도플러 편이, 이동 셀 문제를 NR 절차에 반영했다.
- **작동 원리**: 단말은 위성 또는 지상 게이트웨이를 통해 gNB 기능에 접속한다. 투명 중계형은 위성이 RF 중계만 담당하고, 재생형은 위성에 gNB 기능 일부를 탑재한다.
- **비유**: 지상 기지국이 동네 우체국이라면 LEO NTN은 지구 위를 도는 이동 우체국이다. 우체국이 계속 움직이므로 주소 추적과 배달 시간 보정이 필요하다.
- **구체 예시**: LEO 고도 600km 기준 왕복 전파 지연은 수 ms~수십 ms 범위이며, GEO 약 35,786km의 약 500ms RTT보다 짧아 IoT·문자·저속 데이터에 적합하다.
- **흔한 오해·주의점**: NTN이 지상 5G를 대체하는 것은 아니다. 도심 eMBB는 지상망, 해상·재난·항공 보완은 NTN으로 분리해 판단해야 한다.

## 연결 개념
- 3GPP Release 17 NTN — NR 기반 위성 접속 표준화
- LEO/MEO/GEO — 고도에 따른 지연·커버리지·핸드오버 차이
- 5G SA Core — AMF·SMF·UPF와 NTN 접속 통합

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 출제자가 요구하는 표준, 구조, 적용 조건을 선별해 쓴다.
> 핵심: NTN은 위성 소개가 아니라 3GPP 이동통신망이 지상 한계를 어떻게 보완하는지 쓰는 문제다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NTN은 LEO·MEO·GEO·HAPS를 3GPP NR/5GC와 연동해 지상망 음영을 보완하는 비지상 접속망이다.
> 2. **가치**: 해상·항공·재난·농어촌에서 기지국 백홀 없이 광역 커버리지를 제공하고, 3GPP 절차로 단말·코어 연동성을 확보한다.
> 3. **판단 포인트**: 고도별 RTT, 도플러 보정, 빔 핸드오버, 게이트웨이 가시성, 위성 용량을 함께 판단해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3GPP NTN 구조 이해 확인 | Release 17, LEO 고도 500~2,000km, gNB/UPF 연동 | 위성을 독립 인터넷망으로만 설명 |
| 지상망 대비 적용 조건 판단 | 커버리지, RTT, 도플러, 빔 핸드오버 | LEO와 GEO 지연 차이 누락 |
| 실무 도입 리스크 식별 | 게이트웨이, 주파수, 단말 안테나, SLA 지표 | 도심 5G 대체로 단정 |

> 요약: NTN 답안은 표준 구조와 지연·이동성 제약을 함께 써야 채점 포인트가 맞는다.

## Ⅰ. 개요 및 필요성

NTN은 위성·항공 플랫폼을 포함한 3GPP 비지상 접속망이다. 지상 기지국은 전원·백홀·부지 제약으로 해상·항공·재난 지역 커버리지가 제한된다. LEO 기반 NTN은 낮은 궤도와 다중 위성 빔으로 지상망 음영을 보완한다.

---

## Ⅱ. 구조 및 구성요소

```text
UE/IoT 단말 -> LEO 위성 빔 -> NTN Gateway -> gNB/5GC -> Data Network
                    / 투명 중계
                    / 재생형 gNB 탑재
관제/궤도 정보 -> 빔 관리 -> 핸드오버 -> SLA 관측
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| UE/IoT 단말 | NTN 지원 모뎀으로 위성 빔 접속 | 3GPP NTN Band, GNSS 보정 필요 |
| LEO 위성 | RF 중계 또는 gNB 기능 수행 | 고도 500~2,000km, 빠른 셀 이동 |
| NTN Gateway | 위성과 지상 5GC 연결 | 가시권·백홀·전원 이중화 필요 |
| 5G Core | AMF·SMF·UPF 세션 처리 | 지연 보상 타이머 설정 필요 |

> 요약: NTN 구조는 단말-위성-게이트웨이-5GC를 연결하고, 위성 이동성은 빔 관리와 핸드오버로 처리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
단말 위치 획득 -> 위성 빔 탐색 -> Random Access 보정
-> NTN Gateway 경유 인증 -> PDU Session 설정
-> 빔/위성 핸드오버 -> RTT, RSRP, packet loss 관측
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | GNSS 기반 위치·시간 보정 | timing advance 오차 허용 범위 |
| 2 | 위성 빔 선택 및 접속 | RSRP·SINR 기준 셀 선택 |
| 3 | 5GC 인증·세션 설정 | NAS 타이머, PDU Session 성공률 |
| 4 | 위성 이동에 따른 빔 핸드오버 | handover failure rate 1% 이하 목표 |
| 5 | 트래픽 전달·SLA 관측 | RTT, jitter, packet loss 측정 |

> 요약: NTN은 긴 전파 지연과 위성 이동을 시간 보정·빔 선택·핸드오버 절차로 흡수한다.

## Ⅳ. 특징

| 구분 | 지상 5G | LEO NTN | 판단 포인트 |
|:---|:---|:---|:---|
| 커버리지 | 기지국 반경 수백 m~수 km | 위성 빔 단위 광역 | 해상·항공·재난 지역 |
| 지연 | URLLC 목표 1ms 무선 구간 | LEO RTT 수십 ms 범위 | GEO 약 500ms RTT와 구분 |
| 이동성 | UE 이동 중심 | 위성·빔 이동 동시 발생 | Doppler·beam handover |
| 용량 | 셀 증설로 보강 | 위성 빔·게이트웨이 용량 제한 | eMBB 대체보다 보완망 |

> 요약: LEO NTN은 광역 커버리지에 강점이 있으나 지연·도플러·용량 제약을 지상망과 분리해 설계해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | NTN | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 지상 기지국+광 백홀 | LEO+Gateway+5GC | 부지·전원·백홀 확보 불가 지역 |
| 비용/성능 | 기지국 밀집 투자 | 위성 서비스 구독·게이트웨이 연동 | 트래픽 밀도 낮은 광역 구간 |
| 운영/위험 | 셀 고정 | 위성 이동·빔 전환 | 핸드오버 실패율·SLA 계약 |

> 요약: NTN은 트래픽 밀도보다 커버리지 가치가 큰 업무에서 지상망 보완 수단으로 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 접속 실패 | 긴 RTT와 타이머 불일치 | 3GPP NTN 타이머·TA 보정 | attach success rate |
| 핸드오버 단절 | LEO 빠른 이동과 빔 전환 | 예측 기반 빔 스케줄링 | handover failure rate |
| 용량 병목 | 위성 빔·Gateway 공유 | QoS Class, 트래픽 우선순위 | per-beam throughput |

> 요약: NTN 리스크는 무선 품질보다 시간 보정, 빔 전환, 게이트웨이 병목에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연 | LEO RTT 수십 ms 범위 유지 | ping, TWAMP, UE 로그 |
| 이동성 | 빔 전환 실패율 1% 이하 목표 | RAN 로그, handover trace |
| 가용성 | 재난·해상 구간 서비스 시간 99% 이상 목표 | SLA 리포트, NOC 관측 |

> 요약: NTN 도입 성과는 RTT, 빔 전환 실패율, 서비스 시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 재난·해상·항공 구간을 우선 대상으로 선정하고 3GPP Release 17 NTN 단말, 위성 사업자 SLA, Gateway 경로를 매핑함
2. NAS/RRC 타이머, timing advance, 도플러 보정 값을 LEO 궤도 특성에 맞춰 시험하고 RTT·packet loss 기준선을 수립함
3. 지상 5G, 위성 백홀, 공공망을 SD-WAN 또는 5GC 정책으로 연동해 업무별 QoS와 장애 우회 경로를 분리함

**결론 (2줄):**
- 기술사 판단: 도심 대용량은 지상 5G, 커버리지 공백·재난망은 LEO NTN을 선택하는 혼합망 설계가 타당함
- 향후 방향: Release 18 이후 위성-지상 통합, 직접 단말 접속, IoT NTN이 6G 커버리지 계층으로 확대됨
