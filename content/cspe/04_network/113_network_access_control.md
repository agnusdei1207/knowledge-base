## Ⅰ. 개요
- **정의**: 네트워크 연결 시점에 단말의 보안 상태와 사용자 신원을 검증하여 접근 범위를 제어하는 체계
- **배경/필요성**: BYOD·IoT 확산으로 비인가 단말의 내부망 접속 위험이 증가하여 연결 전 검증이 필요함
- **비유**: 건물 출입 시 신분증 확인과 체온 측정을 동시에 수행하는 보안 게이트와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NAC 아키텍처와 정책 적용 흐름 이해 | 인증-상태점검-격리-허용 4단계 | 에이전트 방식과 에이전트리스 방식 차이 누락 주의 |

> 요약: 단말 보안 상태와 사용자 인증을 기반으로 네트워크 접근을 제어하는 체계임

## Ⅱ. 구성요소
```text
단말(Agent) --> NAC Server --> Policy DB
                  |
          Switch/AP(Enforcer)
                  |
            격리 VLAN / 허용 VLAN
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| NAC Agent | 단말의 OS 패치·백신 상태 등 보안 정보를 수집·전송 | 출입자 건강검진표 |
| NAC Server | 인증·상태 점검 결과를 기반으로 접근 정책을 판단 | 보안 게이트 판단 시스템 |
| Enforcer | 스위치·AP 등에서 VLAN 할당·ACL 적용으로 정책을 집행 | 게이트 차단봉 |
| Policy DB | 접근 정책·보안 기준·예외 규칙을 저장 | 출입 규정 매뉴얼 |

> 요약: Agent-Server-Enforcer-Policy 4요소로 접근 제어를 수행함

## Ⅲ. 절차
```text
단말접속 -> 인증/상태점검 -> 정책판단 -> VLAN할당
```
- 1단계: 단말 접속 — 단말이 네트워크에 연결을 시도하고 Agent가 보안 상태를 수집함
- 2단계: 인증·상태 점검 — NAC Server가 사용자 인증과 단말 보안 상태를 검증함
- 3단계: 정책 판단 — Policy DB 기준으로 허용·격리·차단 중 접근 수준을 결정함
- 4단계: VLAN 할당 — Enforcer가 판단 결과에 따라 허용 VLAN 또는 격리 VLAN을 할당함

> 요약: 접속-점검-판단-할당 4단계로 단말의 접근 범위를 결정함

## Ⅳ. 문제점
- 에이전트 배포 한계: 관리 불가 단말(IoT·BYOD)에 Agent 설치가 불가능 — 보안 사각지대 발생
- 정책 복잡성: 단말 유형·사용자 역할별 세분화된 정책 관리 — 운영 오류 및 정책 충돌 발생
- 네트워크 성능 영향: 모든 연결 시 상태 점검 수행 — 대규모 환경에서 접속 지연 발생

> 요약: 에이전트 미설치·정책 복잡성·성능 영향이 핵심 문제임

## Ⅴ. 개선방안
1. 단기: 에이전트리스 방식(MAC·DHCP 핑거프린팅) 병행으로 비관리 단말 식별 강화
2. 중기: 역할 기반 정책 템플릿과 자동 분류 엔진 도입으로 정책 관리 간소화
3. 장기: 마이크로세그멘테이션 연계로 단말별 최소 권한 적용 및 성능 영향 분산

> 요약: 에이전트리스·정책자동화·마이크로세그멘테이션으로 개선함

## Ⅵ. 전망
- 발전 방향: ZTNA(Zero Trust Network Access)와 통합되어 지속적 검증 체계로 발전함
- 기술사적 판단: 단회 인증에서 지속적 신뢰 평가로의 전환이 NAC의 진화 방향임
- 기술사 제언: SASE·SD-WAN 환경에서 NAC 정책 일관성 확보 전략 수립이 필요함
