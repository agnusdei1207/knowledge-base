## Ⅰ. 개요
- **정의**: 워크로드 단위로 네트워크를 세분화하여 동서 트래픽을 제어하는 보안 기법
- **배경/필요성**: 경계 방화벽은 남북 트래픽만 제어하므로 내부 횡이동 공격에 취약함
- **비유**: 건물 외벽 경비뿐 아니라 각 방마다 별도 잠금장치를 설치하는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 내부 횡이동 방지 원리 | 워크로드 레벨 정책 + 동서 트래픽 제어 | VLAN 세그멘테이션(L2)과 구별: 워크로드 ID 기반 |

> 요약: 워크로드 단위 정책으로 내부 동서 트래픽을 제어하여 횡이동을 차단하는 기법임

## Ⅱ. 구성요소
```text
[Workload A] <--policy--> [Agent]
                             |
                             v
                      [Policy Server]
                             |
                             v
[Workload B] <--policy--> [Agent]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Agent | 각 워크로드에 설치되어 정책 집행 | 방마다 배치된 경비원 |
| Policy Server | 워크로드 ID 기반 허용/차단 정책 중앙 관리 | 출입 규정 본부 |
| Workload Label | 역할·환경·앱 등 메타데이터로 워크로드 식별 | 방 번호와 용도 표시 |
| Visibility Map | 워크로드 간 통신 흐름을 시각화 | 건물 내 동선 지도 |

> 요약: 에이전트-정책서버-레이블-가시성 맵으로 워크로드 간 통신을 제어함

## Ⅲ. 절차
```text
Step1 --> Step2 --> Step3 --> Step4
가시화     레이블링   정책생성   집행/모니터
```
- 1단계: 워크로드 간 통신 흐름을 자동 탐색하여 가시성 맵을 생성함
- 2단계: 워크로드에 역할·환경·앱 등 레이블을 부여함
- 3단계: 레이블 기반 허용/차단 정책을 생성하고 시뮬레이션 검증함
- 4단계: 에이전트가 정책을 집행하고 위반 트래픽을 실시간 모니터링함

> 요약: 가시화-레이블링-정책생성-집행의 4단계로 세그멘테이션을 적용함

## Ⅳ. 문제점
- 에이전트 부담: 모든 워크로드에 에이전트 설치 — 컨테이너·서버리스 환경에서 적용 한계
- 정책 폭증: 워크로드 수 증가에 따라 정책 수가 조합적 증가 — 관리 복잡도 상승
- 성능 오버헤드: 에이전트의 패킷 검사 — 워크로드 CPU·메모리 소비 증가

> 요약: 에이전트 적용·정책 폭증·성능 오버헤드가 대규모 환경에서 과제임

## Ⅴ. 개선방안
1. 단기: eBPF 기반 경량 에이전트로 컨테이너 환경 지원 및 오버헤드 감소
2. 중기: ML 기반 정책 자동 추천으로 정책 생성·갱신 부담 경감
3. 장기: 서비스메시(Istio 등) 연계로 에이전트리스 세그멘테이션 구현

> 요약: 경량 에이전트·정책 자동화·서비스메시 연계로 확장성을 확보할 필요

## Ⅵ. 전망
- 발전 방향: 제로트러스트(064) 아키텍처의 핵심 구현체로 채택 확대
- 기술사적 판단: 클라우드 네이티브 환경에서 네트워크 정책과 ID 기반 정책이 수렴 중임
- 기술사 제언: NDR(063)과 연계하여 동서 트래픽 탐지·차단을 일원화할 필요
