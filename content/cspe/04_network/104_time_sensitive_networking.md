## 미리 알고가기

- 결정형 네트워크는 평균 속도보다 정해진 시간 안에 반드시 도착하는 성질이 중요한 망임
- 시간 동기는 여러 장비의 시계를 같은 기준으로 맞추는 기능임
- 게이트 제어 스케줄은 특정 시간 슬롯에 어떤 트래픽 큐를 열어 둘지 정한 계획표임
- 프레임 선점은 긴 일반 프레임을 잠시 끊고 급한 제어 프레임을 먼저 보내는 기능임

## Ⅰ. 개요

- **정의/개념**: TSN은 표준 이더넷 위에 시간 동기와 예약 전송과 지연 제어 기능을 더해 결정형 통신을 가능하게 하는 기술군임
- **배경/필요성**: 공장 제어와 차량 네트워크와 실시간 미디어는 평균적으로 빠른 것보다 정해진 시간 안에 안정적으로 도착하는 것이 중요하므로 일반 이더넷만으로는 부족함

## Ⅱ. 특징

- 모든 장비가 같은 시간 기준을 공유해 전송 순서를 정밀하게 맞춤
- 예약된 시간 슬롯에 제어 트래픽을 먼저 보내 지연 상한을 줄임
- 일반 트래픽과 실시간 트래픽을 한 망에서 함께 운영할 수 있음
- 시계 오차와 스케줄 불일치는 전송 슬롯 충돌과 지연 상한 초과를 유발함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 이더넷 | TSN |
|:---|:---|:---|
| 지연 보장 | 평균 성능은 좋지만 상한 보장은 약함 | 시간 예약과 우선 제어로 지연 상한을 관리함 |
| 시간 기준 | 장비별 시계 차이를 크게 신경 쓰지 않음 | 정밀한 시간 동기가 필수임 |
| 트래픽 처리 | 혼잡 시 경쟁적으로 큐를 사용함 | 스케줄과 선점과 예약으로 충돌을 줄임 |
| 적합한 환경 | 일반 데이터 통신 | 공장 제어, 차량, 실시간 오디오·비디오 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시간 동기 기능 | 모든 장비의 시계를 맞춰 공통 전송 시점을 형성함 |
| 스케줄 인지 스위치 | 시간표에 따라 큐를 열고 닫아 트래픽을 제어함 |
| 우선순위 큐 | 실시간 프레임과 일반 프레임을 분리해 다룸 |
| 예약과 선점 기능 | 급한 트래픽을 지연 없이 통과시키고 충돌을 줄임 |
| 엔드포인트 | 정해진 주기와 시간표에 맞춰 프레임을 송신함 |

```text
+-----------+    +-----------+    +-----------+    +-----------+
| 시간 동기    | -> | 스케줄 배포   | -> | 예약 전송    | -> | 지연 검증    |
+-----------+    +-----------+    +-----------+    +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 시계 동기화    | -> | 트래픽 분류    | -> | 슬롯 예약      | -> | 우선 전송      | -> | 지연 측정      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **시계 동기화**: 스위치와 단말의 시간을 공통 기준으로 맞춤
2. **트래픽 분류**: 제어 프레임과 일반 데이터를 다른 큐로 나눔
3. **슬롯 예약**: 시간표에 따라 어떤 큐를 언제 열지 정함
4. **우선 전송**: 예약된 슬롯에서 제어 프레임을 먼저 보냄
5. **지연 측정**: 실제 지연과 지터가 목표 범위인지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 공장과 차량 제어망은 TSN이 효과적이지만 시간 동기가 조금만 어긋나도 전체 일정이 흔들리므로 시계 오차와 엔드투엔드 지연과 지터를 함께 계속 확인해야 함
2. 일반 트래픽과 혼합 운용할 때는 예약 슬롯을 너무 넓게 잡으면 데이터망 효율이 떨어지므로 실시간 주기와 일반 트래픽 사용률을 같이 보며 스케줄을 조정해야 함

## Ⅶ. 결론

TSN은 이더넷을 더 빠르게 만드는 기술이 아니라 이더넷을 정해진 시간 안에 예측 가능하게 쓰게 만드는 기술임
