# 📖 【암기용】 개념 완전 이해

> 목적: TSN을 결정형 Ethernet 관점에서 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 표준 Ethernet에 시간 동기와 스케줄링을 넣어 지연 상한을 관리하는 기술군
- **왜 필요한가**: 공장 제어, 차량, 오디오·비디오, 로봇은 패킷이 평균적으로 빨리 오는 것보다 정해진 시간 안에 도착하는 것이 필요하다.
- **핵심 직관**: TSN은 도로 신호등처럼 특정 시간대에 제어 패킷 차선을 열고, 혼잡 패킷이 그 시간대를 침범하지 못하게 한다.

## 깊이 이해
- **배경·문제의식**: 일반 Ethernet은 best-effort 전달이라 혼잡 시 지연과 지터가 커진다. TSN은 IEEE 802.1 표준군으로 시간 동기, 시간 인식 셰이퍼, 프레임 선점, 스트림 필터링을 제공한다.
- **작동 원리**: 802.1AS가 장치 시간을 맞추고, 802.1Qbv가 gate control list로 큐별 전송 시간을 예약한다. 802.1Qci는 스트림별 필터링·폴리싱으로 비정상 트래픽을 차단한다.
- **비유**: 일반 도로에 긴급차 전용 신호와 차선 규칙을 넣어 구급차가 정해진 시간 안에 통과하도록 만드는 방식과 같다.
- **구체 예시**: 1ms 제어 주기 로봇 셀에서 제어 패킷 큐를 200us 시간창에 배치하고, 비제어 트래픽은 나머지 시간창으로 분리한다.
- **흔한 오해·주의점**: TSN은 하나의 프로토콜이 아니라 IEEE 802.1 표준 묶음이다. 적용하려면 시간 동기, 스위치 스케줄, 단말 큐, 검증 도구가 함께 필요하다.

## 연결 개념
- IEEE 802.1AS — 시간 동기
- IEEE 802.1Qbv — 시간 인식 셰이퍼
- IEEE 802.1Qci — 스트림 필터링·폴리싱

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: TSN은 지연 평균값이 아니라 지연 상한, 지터, 시간 동기 오차를 설계·검증하는 Ethernet 확장 기술군이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TSN은 IEEE 802.1AS/Qbv/Qci 등으로 Ethernet 트래픽의 시간 동기, 스케줄링, 필터링을 제공하는 결정형 네트워킹 기술군이다.
> 2. **가치**: 산업 제어와 차량 Ethernet에서 us~ms 단위 지연 상한과 지터 요구를 best-effort Ethernet 위에 구현한다.
> 3. **판단 포인트**: 주기 제어 트래픽, 대역폭 예약, 스위치 지원, 스케줄 검증 도구가 없으면 TSN 도입 효과를 입증하기 어렵다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 결정형 Ethernet 원리 확인 | 802.1AS, 802.1Qbv, 802.1Qci, 지연 상한 | QoS와 TSN을 동일시 |
| 적용 분야 판단 확인 | 산업 제어, 차량 Ethernet, 오디오·비디오 | 일반 인터넷 지연 개선 기술로 설명 |
| 설계 리스크 확인 | 시간 동기, 스케줄 충돌, 장비 호환성 | 표준명 없이 추상 효과만 서술 |

> 요약: TSN 답안은 시간 동기와 큐 스케줄을 중심으로 지연 상한을 어떻게 보장하는지 설명해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 결정형 Ethernet 표준군
- 배경: 일반 Ethernet은 혼잡 시 큐 대기로 지연·지터가 증가해 로봇·차량 제어 주기 보장이 어려움.
- 필요성: 1ms 이하 제어 주기와 us 단위 동기 오차를 요구하는 산업·차량 네트워크에 지연 상한 관리가 필요함.
- 범위: IEEE 802.1AS, 802.1Qbv, 802.1Qci, 802.1Qbu/802.3br 조합으로 판단함.

---

## Ⅱ. 구조 및 구성요소

```text
Talker -> TSN End Station -> TSN Bridge -> TSN Bridge -> Listener
             / 802.1AS Time Sync
             / 802.1Qbv Gate Schedule
             / 802.1Qci Stream Filter
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Talker/Listener | 주기 데이터 송수신 | 스트림 ID 관리 |
| TSN Bridge | 큐 스케줄과 필터링 수행 | 802.1Qbv/Qci 지원 |
| Time Sync | 네트워크 시간 기준 배포 | IEEE 802.1AS |
| Scheduler | gate control list 생성 | 주기·대역폭·경로 반영 |
| Management | 구성·검증·모니터링 | CNC/CUC 모델 |

> 요약: TSN 구조는 시간 동기된 단말과 브리지가 gate schedule에 따라 스트림별 전송 시간을 제어하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 산정 -> 시간 동기 -> 경로/대역폭 예약
-> Gate Control List 배포 -> 주기별 큐 개폐 -> 지연/지터 측정
-> 위반 스트림 필터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 스트림 주기, payload, 지연 상한 정의 | cycle time, latency budget |
| 2 | 802.1AS로 장치 시간 동기화 | sync error |
| 3 | 802.1Qbv로 큐별 시간창 생성 | gate control list |
| 4 | 802.1Qci로 비정상 스트림 차단 | policing drop count |
| 5 | end-to-end 지연과 지터 측정 | p99.999 latency, jitter |

> 요약: TSN은 시간 동기 후 큐별 전송 시간창을 열고 닫아 주기 트래픽의 지연 상한을 검증한다.

## Ⅳ. 특징

| 구분 | 일반 Ethernet QoS | TSN | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 시간 기준 | 장치별 독립 시간 | 802.1AS 동기 | us 단위 동기 오차 목표 |
| 큐 제어 | 우선순위 기반 | 802.1Qbv 시간창 기반 | Gate Control List |
| 이상 트래픽 | 포트·VLAN 정책 | 802.1Qci 스트림 필터 | per-stream policing |
| 적용 영역 | best-effort 업무망 | 산업·차량 제어망 | 1ms cycle 설계 |

> 요약: TSN은 우선순위만 주는 QoS와 달리 시간 동기와 큐 개폐 스케줄로 지연 상한을 설계한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | TSN | 선택 기준 |
|:---|:---|:---|:---|
| 제어망 | 전용 Fieldbus | 표준 Ethernet 기반 결정형 통신 | 벤더 혼재, IP 통합 |
| 지연 관리 | 평균 지연 관리 | 최악 지연·지터 관리 | safety/control traffic |
| 구축 비용 | 전용 장비 | TSN 지원 NIC/Switch | 장비 호환성과 검증 도구 |

> 요약: TSN은 기존 Fieldbus를 모두 대체하는 선택이 아니라 Ethernet 통합과 결정형 지연 요구가 동시에 있을 때 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 스케줄 충돌 | 스트림 주기·경로 계산 오류 | 오프라인 스케줄 검증, CNC 관리 | deadline miss |
| 시간 동기 실패 | GM 장애·링크 지연 변동 | grandmaster 이중화, BMCA 점검 | sync offset |
| 비정상 트래픽 침범 | talker 오류·burst | 802.1Qci policing | dropped frames |

> 요약: TSN 리스크는 스케줄, 시간 동기, 스트림 위반이며 deadline miss와 sync offset으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시간 동기 | sync offset 1us~10us 범위 | gPTP 로그 |
| 지연 상한 | E2E latency budget 이내 | hardware timestamp |
| 지터 | 제어 주기 대비 허용값 이내 | traffic generator |

> 요약: TSN 검증은 평균값보다 시간 동기 오차, E2E 지연 상한, 지터 분포를 확인한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 제어·모니터링·업무 트래픽을 분류하고 각 스트림의 cycle time, payload, deadline, 경로를 명세함.
2. 802.1AS grandmaster와 TSN Switch의 802.1Qbv gate control list를 구성하고 스케줄 충돌을 사전 검증함.
3. 802.1Qci stream filter와 hardware timestamp 측정을 적용해 deadline miss, sync offset, dropped frame을 운영 지표로 관리함.

**결론 (2줄):**
- 기술사 판단: ms 이하 주기 제어와 Ethernet 통합이 동시에 요구되면 TSN을 적용하고, 단순 우선순위 구분이면 VLAN/QoS로 제한함.
- 향후 방향: TSN은 IIoT, 차량 Ethernet, 5G URLLC 연계에서 시간 결정형 데이터 경로의 공통 기반으로 확대됨.
