## Ⅰ. 개요
- **정의**: IP 통신 오류 보고를 수행하는 ICMP와 논리적 IP를 물리적 MAC 주소로 변환하는 ARP임.
- **배경 및 필요성**: IP 계층 자체의 신뢰성 결여 보완 및 이더넷 환경의 대상 물리 주소 파악 목적.
- **출제 의도**: Ping, Traceroute 등 네트워크 진단 원리와 호스트 간 패킷 전달 핵심 매핑 구조 이해 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **ICMP (오류 보고)** | 네트워크 도달 실패, 혼잡 등 통신 오류 및 제어 메시지 전달 | 수취인 불명 안내문 |
| **ARP (IP to MAC)** | 브로드캐스트를 통해 타겟 IP를 가진 단말의 MAC 주소를 질의 | 전체 방송으로 특정인 찾기 |
| **RARP/DHCP** | 자신의 MAC 주소를 기반으로 상위 IP 주소를 할당받는 기법 | 신분증(MAC)으로 임시 통행증 발급 |

> 요약: ICMP는 네트워크 연결 상태를 진단하며, ARP는 IP와 물리적 이더넷 MAC 간 변환 다리 역할을 함.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **[ICMP 진단] Echo Request**: 송신 측이 연결 확인을 위한 ICMP 요청 패킷을 발송함.
2. **[ICMP 응답] Echo Reply**: 목적지가 정상이면 응답을, 불가 시 'Unreachable'를 반환함.
3. **[ARP 질의] ARP Request**: 목적지 MAC을 모를 때 LAN에 브로드캐스트로 MAC을 질의함.
4. **[ARP 응답] ARP Reply**: 대상 IP 기기가 자신의 MAC 주소를 유니캐스트로 응답 후 송신자가 캐싱함.

> 요약: ICMP로 통신 경로를 점검하고, 통신 개시 전 ARP로 목적지의 MAC을 확보해 프레임을 전송함.

## Ⅳ. 문제점
- ICMP Flooding 공격 (원인: 다량의 비정상 ICMP 요청으로 서버 대역폭을 고갈시키는 서비스 거부 공격)
- ARP Spoofing 취약점 (원인: ARP는 별도 인증 절차가 없어 해커가 위조된 응답으로 트래픽을 탈취함)
- 브로드캐스트 오버헤드 (원인: 다수의 ARP 요청 브로드캐스트 패킷이 네트워크 대역폭을 잠식함)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 라우터/방화벽 ICMP Rate Limiting (초당 허용되는 ICMP 응답 수를 제한해 DDoS 예방)
- **중기 방안**: [중기] 동적 ARP 검사(DAI) 설정 (스위치에서 검증되지 않은 위조 ARP 응답 프레임을 자동 차단)
- **장기 방안**: [장기] IPv6 환경 전면 전환 (ARP 브로드캐스트 대신 멀티캐스트 기반의 안전한 NDP 메커니즘으로 완전 대체)

## Ⅵ. 전망
- 레거시 ARP의 보안 취약점은 제로 트러스트 환경 및 IPv6의 NDP 도입으로 근본적 해결을 모색함.
