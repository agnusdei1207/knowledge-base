## Ⅰ. 개요
- **정의**: 인터넷 통신을 4개 계층으로 구분한 실용적 프로토콜 스택 모델
- **배경/필요성**: OSI 7계층(001 참조)의 이론적 복잡성을 줄이고 실제 구현에 적합한 계층 구조가 필요함
- **비유**: 택배 시스템에서 내용물→포장→운송→도로의 4단계 분업과 동일함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OSI 대비 실용적 차이 이해 | 4계층별 대표 프로토콜과 OSI 매핑 | Application 계층이 OSI 5~7 통합임을 누락 |

> 요약: 인터넷 실구현을 위해 4개 계층으로 단순화한 프로토콜 모델임

## Ⅱ. 구성요소
```text
[4] Application    (OSI 5-7)  --- HTTP, FTP, DNS, SMTP
        |
[3] Transport      (OSI 4)    --- TCP, UDP
        |
[2] Internet       (OSI 3)    --- IP, ICMP, ARP
        |
[1] Network Access (OSI 1-2)  --- Ethernet, Wi-Fi
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Application | 사용자 서비스 제공, OSI 5~7 통합 계층 | 편지 작성+봉투 밀봉 |
| Transport | 종단 간 데이터 전달, 포트 기반 다중화 | 택배 추적·보증 |
| Internet | IP 주소 기반 라우팅과 패킷 전달 | 내비게이션 경로 선택 |
| Network Access | 물리 매체 접근과 프레임 전송 | 도로·철도 인프라 |

> 요약: OSI 대비 계층 수를 줄여 실제 프로토콜과 1:1 대응이 용이함

## Ⅲ. 절차
```text
Application --> Transport --> Internet --> Network Access
    |              |             |              |
  Data         Segment        Packet         Frame/Bit
                (port)        (IP addr)      (MAC addr)
```
- 1단계: Application 계층에서 사용자 요청 데이터 생성
- 2단계: Transport 계층에서 포트 번호 부여 및 세그먼트 분할
- 3단계: Internet 계층에서 IP 주소 기반 라우팅 경로 결정
- 4단계: Network Access 계층에서 MAC 주소 기반 프레임 구성 후 물리 전송

> 요약: 각 계층이 주소 체계(포트→IP→MAC)를 기반으로 순차적 캡슐화를 수행함

## Ⅳ. 문제점
- 계층 경계 모호: Application 계층이 OSI 3개 계층 통합으로 세부 분석이 어려움 — 보안·세션 문제 분리 곤란
- 물리 계층 미분리: Network Access가 물리+데이터링크 통합으로 매체별 특성 구분 부족 — 이기종 매체 혼용 시 설계 난이도 증가
- 프로토콜 종속성: IP 중심 설계로 비IP 프로토콜 수용이 제한적 — 산업용 프로토콜 통합에 제약

> 요약: 단순화의 대가로 계층 경계 모호성과 프로토콜 종속성이 발생함

## Ⅴ. 개선방안
1. 단기: OSI 7계층과 교차 매핑 분석으로 보안·세션 기능 분리 설계
2. 중기: SDN/NFV 도입으로 물리 계층 추상화 및 매체 독립적 구성 실현
3. 장기: 비IP 프로토콜 게이트웨이 표준화로 산업용 네트워크 통합 지원

> 요약: OSI 매핑 병행, SDN 추상화, 비IP 통합으로 한계 극복이 필요함

## Ⅵ. 전망
- 발전 방향: 컨테이너 네트워킹(CNI)과 서비스 메시에서 L4/L7 중심 정책 제어로 진화 중
- 기술사적 판단: TCP/IP 모델은 인터넷 아키텍처의 핵심 기반으로 지속 활용됨
- 기술사 제언: 클라우드 환경에서 계층별 보안 정책 수립 시 TCP/IP-OSI 매핑 역량이 필수임
