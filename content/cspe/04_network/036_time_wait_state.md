## 미리 알고가기

- Active Closer는 TCP 연결 종료를 먼저 시작한 쪽임
- MSL은 네트워크 안에서 세그먼트가 살아 있을 수 있는 최대 시간을 뜻함
- TIME_WAIT는 마지막 ACK를 보낸 뒤 2MSL 동안 연결 정보를 잠시 유지하는 상태임
- 지연 중복 세그먼트는 이전 연결에서 늦게 도착한 패킷을 뜻함
- 임시 포트는 클라이언트나 프록시가 외부 연결을 만들 때 잠시 쓰는 로컬 포트임

## Ⅰ. 개요

- **정의/개념**: TIME_WAIT는 TCP 연결 종료 과정에서 마지막 ACK를 보낸 쪽이 2MSL 동안 연결 정보를 유지하는 상태이며, 보통 연결 종료를 먼저 시작한 Active Closer가 이 상태에 들어감
- **배경/필요성**: 마지막 ACK가 유실되거나 이전 연결의 지연 패킷이 늦게 도착하면 새 연결과 섞일 수 있으므로, 연결을 바로 제거하지 않고 짧은 격리 시간을 두어 종료 무결성을 보장해야 함

## Ⅱ. 특징

- TIME_WAIT는 오류 상태가 아니라 정상적인 TCP 종료 절차의 일부임
- 마지막 ACK를 다시 보낼 수 있도록 연결 식별자와 타이머를 잠시 유지함
- 이전 연결의 지연 패킷이 같은 4-튜플로 재사용된 새 연결에 섞이는 일을 막음
- 짧은 연결이 많은 프록시, 로드밸런서, API 게이트웨이에서는 임시 포트와 소켓 엔트리를 많이 점유할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | FIN_WAIT_2 | TIME_WAIT | CLOSE_WAIT |
|:---|:---|:---|:---|
| 들어가는 주체 | 먼저 종료를 시작한 쪽이 상대 FIN을 기다리며 머무름 | 마지막 ACK를 보낸 쪽이 종료 무결성을 위해 머무름 | FIN을 받은 쪽이 애플리케이션 종료를 기다리며 머무름 |
| 머무는 이유 | 상대방이 언제 연결 종료를 마칠지 기다려야 하기 때문임 | ACK 재전송 가능성과 지연 패킷 격리가 필요하기 때문임 | 애플리케이션이 소켓을 닫지 않았기 때문임 |
| 주의해야 할 신호 | 상대 응답 지연이나 비정상 종료가 길어질 수 있음 | 짧은 연결 누적으로 포트 고갈이 생길 수 있음 | 애플리케이션 close 누락이면 누수로 이어질 수 있음 |
| 실무 해석 | 네트워크 반대편 종료 지연을 의심함 | 트래픽 패턴과 연결 재사용 전략을 먼저 점검함 | 애플리케이션 자원 회수를 먼저 점검함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Active Closer | FIN을 먼저 보내 연결 종료를 시작하며, 마지막 ACK를 보낸 뒤 TIME_WAIT에 들어갈 가능성이 큼 |
| 마지막 ACK | 상대방 FIN에 대한 최종 응답이며, 유실되면 상대가 FIN을 다시 보낼 수 있음 |
| 2MSL 타이머 | 지연 패킷이 네트워크에서 사라질 시간을 확보하기 위해 유지하는 대기 시간임 |
| 소켓 엔트리 | 로컬 IP, 로컬 포트, 원격 IP, 원격 포트 조합을 잠시 보관해 같은 식별자의 즉시 재사용을 막음 |

```text
+-------------+     +---------+     +-------------+     +--------+
| 연결 종료 시작 | --> | FIN 송신 | --> | 마지막 ACK 전송 | --> | 2MSL 대기 |
+-------------+     +---------+     +-------------+     +--------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+--------+     +--------+     +--------+     +--------+     +--------+
| FIN 전송 | --> | ACK 수신 | --> | FIN 수신 | --> | ACK 전송 | --> | 타이머 종료 |
+--------+     +--------+     +--------+     +--------+     +--------+
```

1. **FIN 전송**: Active Closer가 연결 종료 의사를 알리기 위해 FIN을 보냄
2. **ACK 수신**: 상대가 FIN을 확인하면 먼저 ACK를 보내고 자신의 정리 작업을 진행함
3. **FIN 수신**: 상대도 종료 준비가 끝나면 FIN을 보내며 연결 종료를 마무리함
4. **ACK 전송**: Active Closer가 마지막 ACK를 보내고 TIME_WAIT 상태로 들어감
5. **타이머 종료**: 2MSL 동안 연결 식별자를 유지한 뒤 소켓 엔트리를 제거함

## Ⅵ. 실무 적용 및 유의점

1. 프록시나 로드밸런서처럼 짧은 외부 연결이 많은 환경에서는 keep-alive, 연결 풀, SNAT 주소·포트 확장으로 TIME_WAIT 누적을 줄이고 `ss -ant state time-wait` 수치와 포트 사용률, 신규 연결 실패율로 효과를 확인함
2. 운영체제 파라미터로 TIME_WAIT 재사용이나 타이머 단축을 검토할 때는 NAT 경유 여부와 지연 패킷 위험을 먼저 점검하고 재전송률, RST 증가 여부, 세션 오류 로그로 부작용을 확인함

## Ⅶ. 결론

TIME_WAIT는 불필요한 지연이 아니라 TCP 종료의 신뢰성을 지키는 장치이므로, 문제의 핵심은 상태 자체보다 짧은 연결 남발과 포트 자원 관리 방식에 있음.
