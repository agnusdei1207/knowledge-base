## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 네트워크를 구성하는 노드와 링크들의 물리적/논리적인 연결 배치 구조 |
| **배경/필요성** | 자원 공유, 장애 허용도, 확장을 고려한 최적의 네트워크 설계 원칙 필요함 |
| **출제 의도** | 각 토폴로지(Star, Mesh, Ring 등)의 장단점 및 트래픽 특성 이해 평가 |

## Ⅱ. 구성요소
```text
+---------+       +---------+
|  Star   |       |  Mesh   |
|   (H)   |       | N --- N |
|  / | \  |       | | \ / | |
| N  N  N |       | N --- N |
+---------+       +---------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Star (성형) | 중앙 허브나 스위치에 모든 노드가 점대점 연결됨 | 중앙집중 터미널 |
| Mesh (망형) | 모든 노드가 서로 점대점으로 연결되어 다중 경로를 가짐 | 그물망 도로망 |
| Ring (링형) | 인접 노드끼리 연결되어 원형의 폐쇄형 구조를 이룸 | 순환 버스 노선 |

> 요약: 요구 성능과 장애 허용도에 따라 적합한 네트워크 토폴로지를 선택해야 함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 요구 분석| -> | 구조 선정| -> | 망 구축  | -> | 성능 검증|
+----------+    +----------+    +----------+    +----------+
```
1. 요구 분석: 대역폭, 노드 수, 예산 및 확장성 요구사항 정의
2. 구조 선정: 분석 결과를 바탕으로 Star, Mesh 등 적합한 구조 결정
3. 망 구축: 스위치/라우터 물리적 배치 및 논리적 세그먼트 구성
4. 성능 검증: 트래픽 병목 지점 및 장애 복구(Failover) 경로 테스트

> 요약: 사전 요구사항 분석부터 구조 선정, 물리적 구축 및 검증 단계로 진행됨

## Ⅳ. 문제점
- Star 구조의 중앙 집중 장비(스위치) 장애 시 전체 마비 유발 (SPOF 원인)
- Full Mesh 구조는 노드 증가에 따라 케이블 및 구축 비용 기하급수 증가
- Ring 구조는 단일 링크 단절 시 전체 순환 통신 끊김 발생 (확장성 한계)

## Ⅴ. 개선방안
- [단기] 코어 및 분배 계층 스위치 이중화(Redundancy)로 Star의 안정성 확보
- [중기] 비용 절감 및 우회 경로 확보를 위한 Partial Mesh 혼합 방식 도입
- [장기] 이중 링(Dual-Ring) 기술 기반의 자가 복구형 아키텍처로 완전성 향상

## Ⅵ. 전망
- 가상화와 SDN 발전으로 물리적 한계를 넘는 논리적 토폴로지 구성이 대세가 될 전망임
