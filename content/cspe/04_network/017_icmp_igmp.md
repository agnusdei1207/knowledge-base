## 미리 알고가기

- ICMP: IP 전송 중 오류와 상태를 알리기 위한 제어 프로토콜임
- IGMP: 호스트가 멀티캐스트 그룹 가입과 탈퇴를 알릴 때 쓰는 프로토콜임
- 멀티캐스트: 같은 데이터를 필요한 수신자 집단에만 전달하는 방식임
- IGMP Snooping: 스위치가 IGMP 메시지를 보고 가입 포트에만 멀티캐스트를 보내는 기능임

## Ⅰ. 개요

- **정의/개념**: ICMP는 IP 계층의 오류와 경로 상태를 알리는 제어 프로토콜이고, IGMP는 IPv4 멀티캐스트 그룹 구성원을 관리하는 제어 프로토콜임
- **배경/필요성**: IP만으로는 전송 실패 원인이나 멀티캐스트 수신자 현황을 알 수 없으므로 장애 정보를 되돌리고 필요한 수신자만 유지하는 절차가 필요함

## Ⅱ. 특징

- ICMP는 도달 불가, 시간 초과, 에코 요청과 응답처럼 오류 보고와 진단에 쓰임
- IGMP는 그룹 가입과 탈퇴를 조정해 멀티캐스트 전달 범위를 제한함
- 두 프로토콜은 사용자 데이터 전달보다 제어와 상태 확인을 담당함
- 과도하게 허용하면 공격 표면이 되고, 무조건 차단하면 진단과 멀티캐스트 운영이 어려워짐

## Ⅲ. 종류 및 비교

| 판단 기준 | ICMP | IGMP |
|:---|:---|:---|
| 주된 목적 | 전송 오류와 경로 상태를 송신자에게 알림 | 멀티캐스트 수신자 집단의 가입과 탈퇴를 관리함 |
| 주요 메시지 | Echo, Destination Unreachable, Time Exceeded, Redirect를 사용함 | Query, Report, Leave를 사용함 |
| 동작 구간 | 송신 호스트와 중간 라우터 사이의 진단과 오류 보고에 쓰임 | 호스트와 첫 홉 라우터 사이의 그룹 관리에 쓰임 |
| 대표 활용 | `ping`, `traceroute`, 경로 문제 분석에 활용함 | IPTV, 실시간 방송, 금융 시세 전송 같은 멀티캐스트에 활용함 |

> 요약: ICMP는 장애와 경로를 알리는 프로토콜이고, IGMP는 멀티캐스트 수신자를 유지하는 프로토콜임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ICMP Type/Code | 어떤 오류와 상태를 알리는지 구분하는 값이며 장애 원인 분석의 직접 단서가 됨 |
| IGMP Querier | 네트워크에서 누가 아직 그룹을 구독하는지 주기적으로 확인하는 라우터 역할임 |
| Host Membership | 어떤 호스트가 어느 멀티캐스트 그룹을 듣는지 나타내며 전달 포트 결정에 쓰임 |
| Snooping Switch | IGMP 제어 메시지를 보고 멀티캐스트를 필요한 포트로만 제한함 |

```text
+--------+      +-----------+      +---------+
| Host   | <--> |  Router   | <--> | Network |
+--------+      +-----------+      +---------+
    |                |
    +-- ICMP 상태 ---+
    +-- IGMP 가입 ---+
```

> 요약: ICMP는 상태를 되돌려 주고, IGMP는 멀티캐스트 수신 대상을 유지해 전달 범위를 정함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상황발생  | --> | 메시지생성 | --> | 수신반응  | --> | 전달갱신 |
+----------+     +----------+     +----------+     +----------+
```

1. **상황발생**: 경로 오류, TTL 초과, 그룹 가입 요청 같은 제어 상황이 발생함
2. **메시지생성**: 라우터나 호스트가 ICMP 또는 IGMP 메시지를 만들어 보냄
3. **수신반응**: 송신자는 장애 원인을 확인하고 라우터는 가입자 목록을 갱신함
4. **전달갱신**: 경로 점검, 장애 분석, 멀티캐스트 포트 제어를 수행함

## Ⅵ. 실무 적용 및 유의점

1. 운영망에서는 진단에 필요한 ICMP 유형은 허용하되 Echo Flood와 Redirect 오용을 제한하도록 유형별 필터를 적용하고 ICMP 차단 건수와 왕복 지연 시간으로 확인함
2. IPTV나 시세 전송망에서는 IGMP Snooping과 Querier를 함께 점검해야 하며 그룹 테이블과 멀티캐스트 트래픽 분포로 불필요한 전달 여부를 확인함

## Ⅶ. 결론

ICMP와 IGMP는 사용자 데이터가 아니라 오류 보고와 멀티캐스트 구성원 관리를 맡는 IP 계층 제어 절차임.

## 작성 근거(검토용)

- ICMP와 IGMP의 공통점은 제어 프로토콜이지만 역할은 다르므로 "보조" 같은 애매한 말 대신 오류 보고와 그룹 관리로 분리함
- 운영 유의점은 허용/차단 당위가 아니라 유형별 필터와 그룹 테이블 확인 기준으로 구체화함
- 결론은 두 프로토콜의 제어 절차 역할을 회수함
