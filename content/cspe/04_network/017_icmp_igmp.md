## 미리 알고가기

- ICMP: IP 전송 중 오류와 상태를 알리기 위한 제어 프로토콜임
- IGMP: 호스트가 멀티캐스트 그룹 가입과 탈퇴를 알릴 때 쓰는 프로토콜임
- 멀티캐스트: 같은 데이터를 필요한 수신자 집단에만 한 번씩 전달하는 방식임
- IGMP Snooping: 스위치가 IGMP 메시지를 보고 실제 가입 포트에만 멀티캐스트를 보내는 기능임

## Ⅰ. 개요

- **정의/개념**: ICMP는 IP 계층에서 발생한 오류와 경로 상태를 알려 주는 제어 프로토콜이고, IGMP는 호스트와 라우터 사이에서 멀티캐스트 수신자 집단을 관리하는 프로토콜임. 둘 다 사용자 데이터를 실어 나르기보다 네트워크가 제대로 동작하도록 보조하는 역할을 맡음
- **배경/필요성**: IP만으로는 전송 실패 원인이나 멀티캐스트 수신자 현황을 알 수 없으므로, 장애 원인을 되돌려 주고 필요한 수신자만 유지하는 별도 제어 절차가 필요함

## Ⅱ. 특징

- ICMP는 도달 불가, 시간 초과, 에코 요청과 응답처럼 오류 보고와 진단 기능을 담당함
- IGMP는 그룹 가입과 탈퇴를 조정해 불필요한 멀티캐스트 전달을 줄이는 데 초점이 있음
- 두 프로토콜 모두 제어 메시지이므로 과도하게 허용하면 공격 표면이 되고, 무조건 차단하면 운영 가시성이 떨어짐
- IPv6 환경에서는 ICMPv6와 MLD로 기능이 재구성되므로 IPv4 설계를 그대로 가져오면 안 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | ICMP | IGMP |
|:---|:---|:---|
| 주된 목적 | 전송 오류와 경로 상태를 송신자에게 알림 | 멀티캐스트 수신자 집단의 가입과 탈퇴를 관리함 |
| 주요 메시지 | Echo, Destination Unreachable, Time Exceeded, Redirect를 사용함 | Query, Report, Leave를 사용함 |
| 동작 구간 | 송신 호스트와 중간 라우터 사이의 진단과 오류 보고에 쓰임 | 호스트와 첫 홉 라우터 사이의 그룹 관리에 쓰임 |
| 대표 활용 | `ping`, `traceroute`, 경로 문제 분석에 활용함 | IPTV, 실시간 방송, 금융 시세 전송 같은 멀티캐스트에 활용함 |

> 요약: ICMP는 장애와 경로를 알리는 데 강하고, IGMP는 멀티캐스트 수신자를 유지하는 데 강함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ICMP Type/Code | 어떤 오류와 상태를 알리는지 구분하는 값이며, 장애 원인을 읽어 내는 가장 직접적인 단서가 됨 |
| IGMP Querier | 네트워크에서 누가 아직 그룹을 구독하는지 주기적으로 확인하는 라우터 역할임 |
| Host Membership | 어떤 호스트가 어느 멀티캐스트 그룹을 듣는지 나타내며, 이 정보가 틀리면 불필요한 트래픽이 퍼짐 |
| Snooping Switch | IGMP 제어 메시지를 보고 멀티캐스트를 필요한 포트로만 제한해 브로드캐스트처럼 퍼지는 문제를 줄임 |

```text
+--------+      +-----------+      +--------+
| Host   | <--> |  Router   | <--> | Network|
+--------+      +-----------+      +--------+
    |                |
    +-- ICMP 상태 ---+
    +-- IGMP 가입 ---+
```

> 요약: ICMP는 상태를 되돌려 주고, IGMP는 멀티캐스트 수신 대상을 유지해 전체 전달 범위를 통제함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 상황발생 | --> | 메시지생성 | --> | 수신측반응 | --> | 전달갱신 |
+----------+     +----------+     +----------+     +----------+
```

1. **상황발생**: 경로 오류, TTL 초과, 그룹 가입 요청 같은 제어 상황이 발생함
2. **메시지생성**: 라우터나 호스트가 ICMP 또는 IGMP 메시지를 만들어 인접 장비에 보냄
3. **수신측반응**: 송신자는 장애 원인을 확인하고, 라우터는 멀티캐스트 가입자 목록을 갱신함
4. **전달갱신**: 경로 점검, 장애 분석, 멀티캐스트 포트 제어 같은 후속 동작을 수행함

## Ⅵ. 실무 적용 및 유의점

1. 운영망에서는 `ping`과 `traceroute` 같은 진단 기능을 위해 필요한 ICMP는 열어 두되 Echo Flood와 Redirect 오용을 막도록 유형별 필터를 적용하고 ICMP 차단 건수와 왕복 지연 시간으로 확인함
2. IPTV나 시세 전송망에서는 IGMP와 Snooping을 함께 써서 가입한 포트에만 멀티캐스트를 보내야 하며 Querier 누락이나 가입 정보 불일치가 생기지 않도록 그룹 테이블과 멀티캐스트 트래픽 분포로 확인함

## Ⅶ. 결론

ICMP와 IGMP는 사용자 데이터보다 눈에 덜 띄지만, 장애 원인을 보이게 하고 멀티캐스트 전달 범위를 통제하는 데 꼭 필요한 제어 프로토콜임.
