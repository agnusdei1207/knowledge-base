# 📖 【암기용】 개념 완전 이해

> 목적: AMI를 전력 계량·통신·운영 플랫폼 관점에서 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 스마트 미터와 전력회사 시스템을 양방향 통신으로 연결하는 원격 검침 인프라
- **왜 필요한가**: 월 1회 수동 검침은 실시간 요금, 정전 감지, 수요반응, 분산전원 관리에 필요한 세밀한 데이터를 제공하지 못한다.
- **핵심 직관**: AMI는 전력량계가 매일 또는 15분 단위로 사용량을 보고하고, 전력회사가 요금·정전·부하 제어를 원격 처리하는 구조이다.

## 깊이 이해
- **배경·문제의식**: 전력망은 태양광, 전기차, 수요반응이 늘면서 배전망 단위 가시성이 필요해졌다. AMI는 스마트 미터, 데이터 집중장치, NAN/WAN, MDMS, HES를 연결한다.
- **작동 원리**: 미터가 kWh, 전압, 전류, 이벤트를 측정하고 PLC, RF Mesh, LTE-M, NB-IoT 등으로 집중장치나 HES에 전송한다. MDMS는 검침값 검증·추정·보정과 과금 연계를 수행한다.
- **비유**: 수도 검침원이 한 달에 한 번 방문하던 방식을 각 계량기가 정해진 시간마다 자동 보고하는 방식으로 바꾼 것이다.
- **구체 예시**: 15분 interval meter data를 하루 96개 생성하고, MDMS가 결측 구간을 VEE 규칙으로 검증한 뒤 요금 시스템에 전달한다.
- **흔한 오해·주의점**: AMI는 원격 검침 장치만 의미하지 않는다. 계량 정확도, 통신 품질, 개인정보, 원격 차단 권한, 장애 복구 절차를 함께 다룬다.

## 연결 개념
- Smart Grid — 전력망 지능화 상위 개념
- NB-IoT/LTE-M — 저전력 광역 통신 후보
- MDMS — 검침 데이터 관리 시스템

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: AMI는 미터 통신만이 아니라 HES·MDMS·요금·정전 관리까지 연결되는 전력 데이터 인프라이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AMI는 스마트 미터, 통신망, HES, MDMS를 연결해 전력 사용량과 이벤트를 양방향 처리하는 원격 계량 인프라이다.
> 2. **가치**: 15분 단위 검침, 원격 개폐, 정전 감지, 수요반응 데이터를 제공해 배전 운영과 과금 정확도를 높인다.
> 3. **판단 포인트**: PLC, RF Mesh, LTE-M, NB-IoT 선택은 밀집도, 지하·농어촌 커버리지, 검침 성공률, 배터리·모듈 비용에 따라 달라진다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스마트그리드 통신 구조 확인 | Smart Meter, DCU, HES, MDMS, Billing | 미터 장치 기능만 서술 |
| 통신망 선택 판단 확인 | PLC, RF Mesh, LTE-M, NB-IoT 비교 | 전국 단일 통신 방식으로 단정 |
| 개인정보·운영 리스크 확인 | 암호화, 인증, 원격 차단 통제, VEE | 사용량 데이터 민감도 누락 |

> 요약: AMI 답안은 계량 데이터 생성부터 과금·정전·수요반응까지 이어지는 데이터 흐름을 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 양방향 원격 계량망
- 배경: 수동 검침은 월 단위 데이터만 제공해 실시간 요금제, 정전 감지, 수요반응 운영에 한계가 있음.
- 필요성: 15분 또는 1시간 interval data를 수집해 부하 예측, 과금, 배전 장애 대응에 활용해야 함.
- 범위: 스마트 미터, 통신망, HES, MDMS, Billing, 보안·개인정보 통제를 포함함.

---

## Ⅱ. 구조 및 구성요소

```text
Smart Meter -> NAN/PLC/RF Mesh/NB-IoT -> DCU/HES -> MDMS -> Billing/OMS/DR
                    / meter event, interval data
                    / remote connect/disconnect
                    / encryption, authentication
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Smart Meter | 전력량·전압·이벤트 측정 | 15분 interval, tamper event |
| NAN/WAN | 미터 데이터를 전송 | PLC, RF Mesh, LTE-M, NB-IoT |
| DCU/HES | 미터 접속·명령·수집 관리 | firmware, remote command |
| MDMS | 검침값 검증·추정·보정 | VEE, data quality |
| 업무 시스템 | 과금·정전·수요반응 연계 | Billing, OMS, DR |

> 요약: AMI 구조는 미터, 통신망, HES, MDMS, 업무 시스템이 계량 데이터와 제어 명령을 양방향으로 처리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용량 측정 -> interval data 생성 -> 통신망 전송 -> HES 수집
-> MDMS VEE 처리 -> Billing/OMS/DR 반영 -> 원격 명령 수행
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 미터가 kWh, 전압, 이벤트를 측정 | 계량 정확도, timestamp |
| 2 | 통신 모듈이 데이터를 전송 | read success rate |
| 3 | HES가 미터별 수집·명령을 관리 | retry, command audit |
| 4 | MDMS가 VEE 규칙으로 데이터 품질 처리 | 결측률, 추정률 |
| 5 | 과금·정전·수요반응 시스템에 반영 | billing exception, outage event |

> 요약: AMI는 미터 측정값을 통신망으로 수집하고 MDMS 검증 후 과금·운영 시스템에 반영한다.

---

## Ⅳ. 특징

| 구분 | 수동/AMR 검침 | AMI | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 데이터 주기 | 월 1회 또는 단방향 | 15분~1시간 interval | 하루 24~96개 값 |
| 통신 | 현장 방문·단방향 | 양방향 원격 통신 | PLC, RF Mesh, LTE-M |
| 운영 | 사후 정산 | 정전·수요반응·원격 개폐 | OMS, DR, remote disconnect |
| 데이터 처리 | 단순 검침 | VEE·품질관리 | MDMS validation |

> 요약: AMI는 검침 자동화를 넘어 전력 사용 데이터와 원격 명령을 배전 운영에 연결한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | AMI | 선택 기준 |
|:---|:---|:---|:---|
| 도시 고밀도 | PLC, RF Mesh | 미터 간 mesh·전력선 활용 | 건물 밀집도, 지하 커버리지 |
| 농어촌 | 장거리 무선 | LTE-M, NB-IoT | 기지국 커버리지, 회선비 |
| 데이터 활용 | 월 검침 | interval+event | 실시간 요금·DR 필요 |

> 요약: AMI 통신 방식은 지역 밀도, 전파 환경, 회선비, 검침 성공률을 기준으로 혼합 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 검침 실패 | 음영지역·PLC 노이즈 | 재시도, DCU 위치 조정, 통신 방식 혼합 | read success rate |
| 개인정보 노출 | 세부 사용 패턴 유출 | AES 암호화, 접근권한, 마스킹 | 접근 로그, 암호화 적용률 |
| 원격 차단 오남용 | 권한·승인 절차 미흡 | 이중 승인, command audit, rollback | command failure, audit gap |

> 요약: AMI 리스크는 수집 실패, 개인정보, 원격 명령 통제이며 성공률과 감사로그로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검침 성공률 | 일별 99% 이상 | HES collection report |
| 데이터 품질 | 결측·추정률 1% 이하 | MDMS VEE report |
| 보안 통제 | 미승인 명령 0건 | IAM, command audit |

> 요약: AMI 운영은 검침 성공률, 데이터 품질, 원격 명령 감사 지표로 평가한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 지역별 밀도와 통신 음영을 조사해 PLC, RF Mesh, LTE-M, NB-IoT를 혼합 설계하고 검침 성공률 기준을 설정함.
2. HES와 MDMS 사이에 VEE 규칙, 재수집 정책, 계량 데이터 보존 기간을 정의하고 과금 예외를 자동 식별함.
3. 미터 인증서, 암호화, 원격 차단 이중 승인, command audit을 적용해 사용량 데이터와 제어 명령을 통제함.

**결론 (2줄):**
- 기술사 판단: AMI는 단말 보급률보다 검침 성공률·VEE 품질·원격 명령 감사 체계가 운영 성패를 좌우함.
- 향후 방향: AMI는 전기차 충전, 분산전원, 수요반응과 연계되어 배전망 데이터 플랫폼 역할을 확대함.
