## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 내부 사설 IP를 외부 공인 IP로 변환하여 제한된 IPv4 주소 공간을 효율적으로 공유하는 기술 |
| **배경/필요성** | 인터넷 팽창으로 인한 IPv4 주소 고갈 위기 지연 및 내부 망의 보안성 확보 필요 |
| **출제 의도** | 사설 망과 공인 망 간의 주소 변환(NAT) 및 포트 기반 다중화(PAT) 동작 원리 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Private |       |   NAT    |       |  Public  |
|  (Host)  | <---> | (Router) | <---> | (Internet|
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 사설 IP | 인터넷 라우팅이 불가능하며 조직 내부에서만 독자적으로 재사용하는 주소 | 사내 내선 번호 |
| NAT | 1:1 또는 N:M으로 사설 IP를 공인 IP로 단순 변환하는 방식 | 외부 발신 번호 변환기 |
| PAT (NAPT) | IP 변환 시 포트 번호(Port)까지 결합하여 하나의 공인 IP로 다수 단말 수용 | 구내 교환기(PBX) |

> 요약: 공인 IP 하나에 포트 번호를 매핑(PAT)하여 다수의 내부 단말이 동시 통신할 수 있게 함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 패킷 생성| -> | 변환 테이블| -> | 외부 전송| -> | 역변환   |
+----------+    +----------+    +----------+    +----------+
```
1. 패킷 생성: 내부 단말이 목적지 외부 서버를 향해 사설 IP 소스 패킷 전송
2. 변환 테이블: NAT 라우터가 사설 IP/포트를 공인 IP/고유 포트로 변환하고 NAT 테이블에 매핑 기록
3. 외부 전송: 변환된 공인 IP를 달고 인터넷을 통해 외부 서버에 안전하게 도달
4. 역변환: 외부 서버의 응답을 수신한 NAT 라우터가 매핑 테이블을 조회해 원본 사설 IP로 환원 및 전달

> 요약: 변환 테이블(Mapping)을 생성하고 패킷의 Source/Destination IP를 변경하여 중계함

## Ⅳ. 문제점
- IP 헤더 및 TCP/UDP 포트를 직접 조작하므로 IPSec이나 SIP 등 특정 프로토콜 작동 실패 원인
- 세션 테이블 크기 제한으로 인해 대규모 트래픽 발생 시 메모리 부족으로 신규 연결 거부 (성능 병목)
- 종단 간(End-to-End) 추적이 단절되어 P2P 통신 서비스 및 서버 구축이 복잡해지는 단점

## Ⅴ. 개선방안
- [단기] ALG(Application Level Gateway) 기능을 라우터에 활성화하여 SIP, FTP 통신의 NAT 간섭 우회
- [중기] 다중 공인 IP 풀(Pool)을 활용한 동적 NAT 분산 구성으로 라우터 NAT 테이블 부하 완화
- [장기] 근본적인 IP 주소 확장 및 종단 간 투명성을 보장하는 IPv6 네이티브 망으로 전면 전환

## Ⅵ. 전망
- IPv6 보급이 가속화됨에 따라 단순 주소 절약 용도보다는 보안 격리 기능으로 역할이 축소될 전망임
