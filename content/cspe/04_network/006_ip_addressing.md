## Ⅰ. 개요
- **정의**: 네트워크 상 호스트를 고유하게 식별하기 위한 논리적 주소 체계
- **배경/필요성**: 물리 주소(MAC)만으로는 라우팅이 불가하여 계층적 논리 주소가 필요함
- **비유**: 전국 우편번호 체계와 동일 — 지역(네트워크부)+상세주소(호스트부)로 구분함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IPv4 클래스 구조와 특수 주소 이해 | 클래스 A~E 범위, 사설 IP 대역, 서브넷 마스크 | 클래스 경계 IP 범위 오류 |

> 요약: 네트워크부+호스트부로 구성된 계층적 논리 주소로 라우팅을 가능하게 함

## Ⅱ. 구성요소
```text
IPv4 Address (32 bit)
|<-- Network -->|<-- Host -->|
|   10.0.       |  1.25      |
+---+---+---+---+
| 8 | 8 | 8 | 8 | (Octet)
+---+---+---+---+

Class A: 0xxx / 8bit Net  / 1.0.0.0 ~ 126.x.x.x
Class B: 10xx / 16bit Net / 128.0.0.0 ~ 191.x.x.x
Class C: 110x / 24bit Net / 192.0.0.0 ~ 223.x.x.x
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 네트워크부 | 호스트가 속한 네트워크 식별 영역 | 우편번호의 시·군·구 |
| 호스트부 | 네트워크 내 개별 호스트 식별 영역 | 상세 주소(동·호수) |
| 서브넷 마스크 | 네트워크부와 호스트부 경계를 결정하는 비트 마스크 | 구역 경계선 |
| 사설 IP | 내부 네트워크 전용 주소(10.x, 172.16~31.x, 192.168.x) | 아파트 내부 호수 |

> 요약: 네트워크부·호스트부·서브넷 마스크로 계층적 주소 구조를 형성함

## Ⅲ. 절차
```text
[IP 할당 계획] --> [클래스/CIDR 결정] --> [서브넷 분할] --> [호스트 배정]
```
- 1단계: 조직 규모와 네트워크 수 파악하여 필요 주소 수 산정
- 2단계: 클래스 기반 또는 CIDR(007 참조) 방식으로 주소 블록 결정
- 3단계: 서브넷 마스크 설정으로 네트워크를 논리적 세그먼트로 분할
- 4단계: 각 서브넷 내 호스트에 IP 수동 할당 또는 DHCP(010 참조) 자동 할당

> 요약: 규모 산정→블록 결정→서브넷 분할→호스트 배정의 순서로 IP를 체계적으로 할당함

## Ⅳ. 문제점
- 주소 고갈: IPv4의 약 43억 개 주소가 인터넷 디바이스 증가로 고갈 — IoT 확산으로 가속화
- 클래스 낭비: 클래스 단위 할당 시 미사용 주소 대량 발생 — Class A의 호스트 1,600만 개 중 일부만 사용
- 라우팅 테이블 비대: 비체계적 할당으로 경로 집약 곤란 — 라우터 메모리·처리 부담 증가

> 요약: 주소 고갈, 클래스 낭비, 라우팅 비대화가 IPv4 주소 체계의 핵심 한계임

## Ⅴ. 개선방안
1. 단기: CIDR 기반 가변 길이 할당으로 클래스 낭비 최소화
2. 중기: NAT/PAT(009 참조) 적용으로 사설 IP 재사용하여 공인 주소 절감
3. 장기: IPv6(008 참조) 전환으로 128비트 주소 공간 확보 및 라우팅 효율화

> 요약: CIDR, NAT, IPv6 순으로 주소 고갈과 낭비를 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: IPv6 전환 가속과 함께 듀얼스택·터널링 병행 운용이 확대 중
- 기술사적 판단: IPv4 주소 체계 이해는 서브네팅·CIDR·NAT 설계의 전제 조건임
- 기술사 제언: IPv4/IPv6 공존 환경에서 주소 설계·전환 전략 수립 역량이 필요함
