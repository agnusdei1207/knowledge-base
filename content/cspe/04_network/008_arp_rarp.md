# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 논리적 주소인 IP와 물리적 주소인 MAC을 서로 연결해주는 **주소 변환 프로토콜**입니다.
- **필요성**: 우리는 상대방의 IP 주소는 알지만, 실제 데이터를 실어 나르는 랜카드 번호(MAC)는 모릅니다. 이때 IP를 들고 가서 "이 IP 주인 누구야? MAC 주소 좀 알려줘!"라고 묻는 과정이 필요합니다.
- **핵심 직관**: **"IP(이름)로 MAC(주민번호) 찾기"**.

## 깊이 이해
- **배경 (왜 두 번 물어볼까?)**: TCP/IP 통신을 하려면 3계층(IP) 정보와 2계층(MAC) 정보가 모두 필요합니다. 하지만 사용자나 앱은 IP만 다루죠. 그래서 실제 전선으로 데이터를 쏘기 직전에 하위 계층의 주소를 알아내는 단계가 반드시 필요합니다.
- **작동 원리 (ARP의 2단계)**:
  1.  **ARP Request**: "IP 192.168.0.10인 사람 손들어!"라고 모든 장비에 외칩니다 (**Broadcast**).
  2.  **ARP Reply**: "저요! 제 MAC은 AA:BB:CC입니다."라고 요청자에게만 답합니다 (**Unicast**).
- **RARP (Reverse ARP)**: 반대로 자기 MAC 주소는 아는데 IP를 모를 때(디스크가 없는 단말기 부팅 시 등) 서버에 IP를 물어보는 방식입니다. 현재는 **DHCP**가 이 역할을 대신하며 거의 쓰이지 않습니다.
- **ARP Cache**: 매번 물어보면 비효율적이니, 한 번 알아낸 IP-MAC 쌍은 메모리에 잠시 저장해 둡니다.

## 연결 개념
- **ARP Spoofing**: 가짜 ARP 응답을 보내 상대방의 통신을 가로채는 공격. ARP가 응답의 진위여부를 확인하지 않는 점을 악용합니다.
- **GARP (Gratuitous ARP)**: 요청이 없어도 자기 정보를 광고하는 것. IP 충돌 감지나 장비 교체 시 주변 기기의 정보를 갱신할 때 씁니다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 네트워크 계층(L3)의 IP 주소를 데이터링크 계층(L2)의 MAC 주소로 동적으로 매핑하는 주소 해소(Resolution) 프로토콜임.
> 2. **가치**: IP 기반의 논리적 통신 스택을 실제 물리 하드웨어 전송 스택과 결합하여 이기종 망 간 데이터 도달을 실현함.
> 3. **판단 포인트**: ARP는 무인증(Stateless) 구조로 인해 스푸핑 보안 위협에 노출되어 있으므로, DAI(Dynamic ARP Inspection) 등 인프라 기반 통제가 필수적임.

## Ⅰ. ARP와 RARP의 정의 및 필요성
- **ARP (Address Resolution Protocol)**: 목적지 IP 주소에 해당하는 물리적 MAC 주소를 알아내기 위한 프로토콜.
- **RARP (Reverse ARP)**: 물리적 MAC 주소를 바탕으로 논리적 IP 주소를 할당받기 위한 프로토콜.
- **필요성**:
  - **계층 간 간극 해소**: 상위 계층(IP)의 논리 주소를 하위 계층(MAC)의 물리 주소로 변환하여 프레임 캡슐화 완성.
  - **동적 관리**: 장치 이동이나 변경 시에도 수동 설정 없이 주소 매핑 정보 자동 갱신.

## Ⅱ. ARP의 동작 메커니즘 상세 프로세스

### 1. ARP Request & Reply 과정
1. **ARP Cache 조회**: 송신 호스트는 목적지 IP가 자신의 캐시 테이블에 있는지 먼저 확인.
2. **Request (Broadcast)**: 캐시에 없으면 목적지 MAC을 `FF:FF:FF:FF:FF:FF`로 설정하여 LAN 전체에 방송.
3. **Reply (Unicast)**: 해당 IP를 보유한 호스트만 자신의 MAC 주소를 담아 요청자에게 1:1 응답.
4. **Update**: 송신 호스트는 수신한 정보를 캐시에 저장하고 실제 데이터 프레임 전송 시작.

### 2. ARP Cache 테이블 관리
- **Dynamic Entry**: 일정 시간(Aging Time) 동안 통신이 없으면 자동 삭제하여 테이블 정합성 유지.
- **Static Entry**: 보안이나 성능 목적상 관리자가 수동으로 고정.

## Ⅲ. 특수 목적의 ARP: GARP 및 Proxy ARP

### 1. GARP (Gratuitous ARP)
- **정의**: 요청자가 없어도 자신의 IP/MAC 정보를 브로드캐스트로 전송.
- **용도**: IP 주소 충돌 감지, 클러스터링(H/A) 환경에서 Master 전환 시 인접 스위치의 MAC 테이블 갱신 유도.

### 2. Proxy ARP
- **정의**: 라우터가 특정 호스트를 대신하여 ARP 응답을 보내는 기법.
- **용도**: 서브넷 마스크가 다른 호스트 간 통신이나 VPN 원격 접속 시 물리적 위치를 은폐하고 연결 지원.

## Ⅳ. ARP 기반 보안 위협 및 방어 전략

### 1. ARP Spoofing (Poisoning)
- **위협**: 공격자가 위조된 ARP Reply를 지속적으로 보내, 타겟 호스트의 캐시 테이블에 공격자의 MAC을 게이트웨이 주소로 오염시켜 데이터를 가로챔.
- **공격 원리**: ARP가 요청 이력을 확인하지 않고 먼저 도착한 Reply를 신뢰하는 점을 악용.

### 2. 대응 기술
- **Static ARP**: 주요 서버 및 게이트웨이의 MAC 주소를 수동 고정.
- **DAI (Dynamic ARP Inspection)**: 스위치에서 DHCP Snooping 바인딩 테이블과 대조하여 위조된 ARP 패킷을 물리 포트 수준에서 차단.

## Ⅴ. ARP vs RARP vs NDP 비교

| 비교 항목 | ARP | RARP | NDP (IPv6) |
|:---:|:---|:---|:---|
| **기능** | IP → MAC | MAC → IP | IPv6 → MAC |
| **작동 계층** | L2 (Ethernet 위) | L2 (Ethernet 위) | L3 (ICMPv6 기반) |
| **전송 방식** | Broadcast | Broadcast | Multicast (효율적) |
| **현재 위상** | 핵심 표준 | DHCP로 대체됨 | 차세대 표준 (ARP 기능 포함) |

## Ⅵ. 기술사적 통찰: '신뢰'와 '보안'의 트레이드오프
- **인터넷의 원형**: ARP는 초기 인터넷의 '상호 신뢰' 환경에서 설계되어 보안 고려가 부족함. 이는 현대 네트워크 보안에서 가장 취약한 'L2 보안'의 핵심 이슈가 됨.
- **SDN으로의 진화**: 현대적 SDN(Software Defined Networking) 환경에서는 브로드캐스트 부하를 줄이기 위해 컨트롤러가 ARP 요청을 가로채서 유니캐스트로 응답하는 ARP Proxying 기법을 적극 활용함.
- **결론**: ARP는 네트워크 통신의 성립을 위한 가장 기초적인 약속이며, 이 메커니즘을 완벽히 이해하는 것이 L2 스위칭 보안과 이중화 설계의 출발점임.
