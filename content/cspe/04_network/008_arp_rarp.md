## 미리 알고가기

- ARP: IPv4 주소에 대응하는 MAC 주소를 같은 LAN에서 찾는 프로토콜임
- RARP: MAC 주소로 IP 주소를 얻던 과거 방식이며 현재는 DHCP가 역할을 대체함
- ARP Cache: IP와 MAC 매핑을 일정 시간 저장하는 테이블임
- Gratuitous ARP: 자신의 IP와 MAC 매핑을 네트워크에 알리거나 중복 주소를 확인할 때 쓰는 ARP임

## Ⅰ. 개요

- **정의/개념**: ARP는 IPv4 패킷을 같은 LAN에서 프레임으로 보내기 위해 목적지 IP에 대응하는 MAC 주소를 찾는 주소 해석 프로토콜임
- **배경/필요성**: 라우팅은 IP 주소로 다음 홉을 정하지만 실제 이더넷 전송은 MAC 주소가 필요하므로 두 주소 체계를 연결하는 절차가 필요함

## Ⅱ. 특징

- ARP Request는 브로드캐스트로 전송되고 ARP Reply는 보통 유니캐스트로 응답함
- ARP Cache는 반복 질의를 줄이지만 오래된 매핑이 남으면 통신 장애를 만들 수 있음
- ARP는 기본적으로 응답의 진위를 검증하지 않아 스푸핑 공격에 취약함
- RARP는 기능상 DHCP로 대체되었으므로 현대 답안에서는 역사적 비교 수준으로 다룸

## Ⅲ. 종류 및 비교

| 판단 기준 | ARP | RARP |
|:---|:---|:---|
| 변환 방향 | IPv4 주소로 MAC 주소를 찾음 | MAC 주소로 IPv4 주소를 얻음 |
| 사용 위치 | IPv4 LAN의 현재 주소 해석에 쓰임 | 디스크리스 장비 초기 부팅에 쓰이던 방식임 |
| 현재성 | IPv4 운영에서 여전히 필요함 | DHCP와 BOOTP로 대체되어 실무 사용이 제한적임 |
| 주의점 | 스푸핑과 캐시 오염을 통제해야 함 | 현대 설계의 주요 선택지가 아님 |

> 요약: ARP는 현재 IPv4 LAN 전달에 필요한 절차이고 RARP는 DHCP 이전의 역방향 주소 획득 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ARP Request | 목적지 IP의 MAC 주소를 묻기 위해 LAN 전체에 보내는 질의임 |
| ARP Reply | 해당 IP를 가진 장비가 자신의 MAC 주소를 알려 주는 응답임 |
| ARP Cache | 확인한 매핑을 저장해 매번 브로드캐스트하지 않게 하는 테이블임 |
| 보안 기능 | DHCP Snooping과 DAI가 정상 매핑을 기준으로 위조 ARP를 걸러냄 |

```text
+--------+      broadcast       +--------+
| Host A | --- ARP Request ---> |  LAN   |
+--------+                     +--------+
| Host B | <--- ARP Reply ----- | Host A |
+--------+      unicast        +--------+
```

> 요약: ARP는 캐시 확인, 브로드캐스트 질의, 유니캐스트 응답, 캐시 저장 순서로 IP와 MAC을 연결함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 다음홉확인 | --> | 캐시조회  | --> | ARP질의  | --> | 매핑저장 |
+----------+     +----------+     +----------+     +----------+
```

1. **다음홉확인**: 목적지가 같은 서브넷이면 목적지 IP, 아니면 게이트웨이 IP를 해석 대상으로 삼음
2. **캐시조회**: ARP Cache에 매핑이 있으면 바로 프레임을 생성함
3. **ARP질의**: 매핑이 없으면 브로드캐스트로 대상 IP의 MAC 주소를 물음
4. **매핑저장**: 응답 MAC을 캐시에 저장하고 목적지 MAC으로 프레임을 전송함

## Ⅵ. 실무 적용 및 유의점

1. 사내 LAN에서는 ARP 스푸핑이 게이트웨이 위장으로 이어질 수 있으므로 DHCP Snooping과 DAI를 함께 적용하고 위조 ARP 차단 로그와 게이트웨이 MAC 변동 이력으로 확인함
2. 서버 이중화나 IP 이동 환경에서는 Gratuitous ARP가 캐시 갱신을 돕지만 장비별 반영 시간이 달라질 수 있으므로 장애 조치 후 ARP Cache와 접속 실패율을 확인함

## Ⅶ. 결론

ARP는 IPv4 라우팅 결과를 실제 LAN 프레임 전달로 연결하는 절차이며, 운영에서는 캐시와 위조 응답 통제가 함께 필요함.

## 작성 근거(검토용)

- ARP는 IP와 MAC 매핑보다 다음 홉을 프레임으로 보내는 절차가 답안 흐름을 결정하므로 원리 흐름을 그 기준으로 작성함
- RARP는 현재성 낮은 기술이므로 ARP와 같은 비중의 개선 대상처럼 쓰지 않고 비교표에서 위치만 정리함
- 보안 통제 표현은 DAI, DHCP Snooping, 게이트웨이 MAC 변동 확인으로 구체화함
