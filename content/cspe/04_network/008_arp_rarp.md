# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: ARP·RARP는 논리 주소(IP)와 물리 주소(MAC)를 서로 짝지어 주는 주소 변환 프로토콜로, L3와 L2의 간극을 이어 줌 (IP는 004, MAC은 007 참조).
- **왜 필요한가**: 실제 프레임은 MAC 기반으로 전달되므로, 목적지 IP만 알아서는 프레임을 만들 수 없고 그 IP에 대응하는 MAC을 먼저 알아내야 함.
- **핵심 직관**: 교실에서 "10번(IP) 누구야?" 외치면(브로드캐스트) 한 명이 "저요, 3열 2번(MAC)입니다"라고 답(유니캐스트)하는 것이 ARP임.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안(Ⅰ~Ⅵ·표)에 나오는 것들을 미리 풀어 둔 것임. 최상위 키워드는 **IP↔MAC 매핑**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| ARP (Address Resolution Protocol) | IP 주소로 상대 MAC을 알아내는 프로토콜 | 이름 부르면 자리번호 답하기 |
| RARP (Reverse ARP) | 자기 MAC으로 자기 IP를 서버에 물어보는 옛 프로토콜 | 사원증만 들고 "제 이름이 뭐죠?" |
| Broadcast (브로드캐스트) | 세그먼트 전체 노드에게 동시 전송(`FF:FF:FF:FF:FF:FF`) | 온 교실에 대고 외치기 |
| Unicast (유니캐스트) | 특정 한 노드에게만 1:1 전송 | 지목한 한 명에게만 답 |
| ARP Cache | 알아낸 IP-MAC 쌍을 임시 저장하는 표 | 한번 외운 자리번호 메모 |
| Cache Aging | 동적 ARP 항목을 일정 시간(예: 300초) 후 삭제 | 메모를 며칠 뒤 지우기 |
| GARP (Gratuitous ARP) | 응답을 바라지 않고 자기 IP-MAC을 자발적 공지 | "저 여기 있어요" 일방 방송 |
| Stateless | 요청 이력을 안 따지고 도착한 Reply를 그냥 신뢰 | 안 물어봤는데 온 답도 받아 적음 |
| ARP Spoofing | 게이트웨이 MAC인 척 가짜 Reply로 트래픽 가로채기 | 가짜 안내원이 손님 편지 가로챔 |
| DAI (Dynamic ARP Inspection) | 스위치가 DHCP 바인딩과 안 맞는 ARP를 차단 | 위조 안내원을 문에서 검문 |
| Default Gateway | 다른 서브넷으로 나갈 때 거치는 출구 라우터 | 건물 정문 |
| NDP / NS·NA | IPv6에서 ARP를 대체하는 이웃 탐색(ICMPv6) | ARP의 IPv6판 |

## 깊이 이해
- **배경·문제의식**: 사용자·앱은 IP(L3)만 다루지만 스위치·NIC은 MAC(L2)으로 동작함. 이 두 계층을 잇는 동적 매핑 테이블이 필요해 ARP가 등장함.
- **작동 원리(어떻게+왜)**:
  - ARP: "IP 192.168.0.5 쓰는 분, MAC이 뭡니까?"를 브로드캐스트로 묻고, 당사자만 유니캐스트로 답하며, 그 결과를 ARP 캐시에 저장해 재요청을 줄임.
  - RARP: 디스크 없는 단말이 부팅 시 자기 MAC만으로 "제 IP가 뭐죠?"를 서버에 물어 IP를 받아오던 옛 방식으로, 현재는 DHCP(009)가 대체함.
- **비유**: ARP는 이름(IP)으로 자리번호(MAC)를 알아내는 것, RARP는 자리번호만 들이밀며 이름을 되묻는 것임.
- **구체 예시**: 외부 웹서버(1.1.1.1)로 보낼 때 목적지가 다른 서브넷이면, 내 PC는 서버 MAC이 아니라 게이트웨이 IP에 ARP를 던져 게이트웨이 MAC을 알아낸 뒤 프레임을 씌워 보냄.
- **흔한 오해·주의점**: ARP Request는 브로드캐스트라 세그먼트 전체로 퍼짐. 단말이 많으면 ARP 폭주가 생기고, "내가 게이트웨이야"라고 속이는 ARP Spoofing에 매우 취약함.

## 연결 개념
- MAC 주소 (007 참조) — ARP가 알아내려는 대상 물리 주소.
- ARP Spoofing/Poisoning — 위조 Reply로 캐시를 오염시키는 중간자(MITM) 공격.
- DHCP (009 참조) — RARP를 대체해 IP·넷마스크·게이트웨이까지 함께 알려주는 현대 프로토콜.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ARP는 논리 IP를 물리 MAC으로 동적 바인딩하는 매핑 프로토콜이고, RARP는 그 역(MAC→IP)으로 현재는 DHCP로 대체됨.
> 2. **가치**: 사용자·앱이 하드웨어 주소를 몰라도 IP만으로 이더넷 프레임 캡슐화가 가능하게 하여 L3-L2 통신을 성립시킴.
> 3. **판단**: 무결성 검증이 없는 Stateless 구조라 스푸핑에 취약하므로, 기업망은 DHCP Snooping+DAI와 핵심 자산 Static ARP가 필요함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| L3-L2 변환 원리 파악 | Request(브로드캐스트)→Reply(유니캐스트) 과정 | L3 라우팅과 L2 스위칭 동작을 혼동 서술 |
| ARP·RARP 차이 식별 | ARP(IP→MAC), RARP(MAC→IP, DHCP로 대체됨) | RARP가 현재도 널리 쓰이는 듯 서술 |
| 보안 취약점 대처 | 위조 Reply 원리와 DAI·Static ARP 방어 | 공격 원리만 쓰고 스위치 단 차단책 누락 |

> 요약: 메커니즘은 단순하므로 통신 성립의 전제라는 점과 무인증 구조의 취약점 대응으로 논리를 전개해야 함.

## Ⅰ. 개요 및 필요성

- 정의: IP를 MAC으로 변환하는 ARP와 그 역과정 RARP로 계층 간 주소를 매핑하는 통신 규약임.
- 배경: 앱은 IP(L3)로 통신을 시도하나 이더넷 구간 전송은 MAC(L2)이 필수로 요구됨.
- 필요성: 대상 호스트·게이트웨이의 MAC을 동적으로 알아내 이더넷 프레임을 캡슐화하기 위함임.

---

## Ⅱ. 구조 및 구성요소

구조도(선형):

```text
Host A(192.168.0.10) -> ARP Request "0.20의 MAC?" 브로드캐스트 -> 세그먼트 전체
  -> Host B(192.168.0.20)만 인식 -> ARP Reply "제 MAC은 BB:CC" 유니캐스트 -> Host A
  -> Host A가 ARP Cache 갱신 후 데이터 프레임 전송
```

| 구성요소 | 목적 | 탐색 방식 | 현재 위상 |
|:---|:---|:---|:---|
| ARP | 타겟 IP로 타겟 MAC 식별 | Request 브로드캐스트 → Reply 유니캐스트 | 이더넷 필수 표준 |
| RARP | 자기 MAC으로 할당 IP 요청 | Request 브로드캐스트 → 서버 응답 | 디스크리스용, DHCP로 대체 |
| GARP | 자기 IP-MAC을 자발적 공지 | 응답 불필요 브로드캐스트 | IP 충돌 감지·HA 절체 시 캐시 갱신 |

> 요약: ARP는 L3를 L2로 해석하는 필수 브릿지이고, RARP는 그 역과정, GARP는 상태 변경 시 캐시를 빠르게 갱신함.

---

## Ⅲ. 동작원리 및 흐름도

흐름도(선형):

```text
통신 요청(IP 기반) -> ARP Cache 조회
  -> 있으면 즉시 프레이밍 / 없으면 ARP Request 브로드캐스트
  -> 목적지 호스트만 ARP Reply 유니캐스트 -> 송신 PC가 Cache 기록 -> 보류 패킷 전송
```

- 1단계: 송신 PC가 ARP 캐시에서 목적지 IP의 MAC 존재 여부를 조회함(캐시 룩업).
- 2단계: 캐시에 없으면 목적지 MAC을 `FF:FF:FF:FF:FF:FF`로 채워 ARP Request를 브로드캐스트함.
- 3단계: 세그먼트 내 모든 노드가 패킷을 확인하되, IP가 일치하는 호스트만 ARP Reply를 유니캐스트로 회신함.
- 4단계: 송신 PC가 응답으로 캐시를 갱신하고 보류했던 IP 패킷을 프레이밍하여 전송함.

> 요약: 요청은 브로드캐스트라 부하가 크므로, 한번 알아낸 매핑은 Cache에 저장해 Aging 시간까지 재사용함.

---

## Ⅳ. 특징

- 무인증 신뢰(Stateless): 요청하지 않았어도 도착한 Reply를 검증 없이 캐시에 기록하여, ARP Spoofing 성립의 근본 원인이 됨.
- 로컬 세그먼트 한정: ARP 브로드캐스트는 라우터를 넘지 못해 동일 서브넷 내에서만 동작하며, 외부 통신은 항상 게이트웨이 MAC을 대상으로 함.
- 캐시 에이징: 동적 항목은 일정 시간(예: 300초) 후 삭제되어, 장비 교체 시 최신 MAC으로 자연 갱신됨.
- 단순·저부하 대비 확산 비용: 매핑 자체는 가볍지만 브로드캐스트가 세그먼트 전체를 인터럽트해 대규모 망에서 폭주 위험이 있음.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | ARP | RARP | GARP |
|:---|:---|:---|:---|
| 방향 | IP → MAC | MAC → IP | 자기 IP-MAC 공지 |
| 응답 기대 | 유니캐스트 Reply 수신 | 서버가 IP 회신 | 응답 없음(일방) |
| 주 용도 | 통신 전 목적지 MAC 확보 | 디스크리스 단말 부팅 IP | IP 충돌 감지·HA 절체 캐시 갱신 |
| 현재 위상 | 필수 표준 | DHCP로 대체됨 | 이중화·DAD 보조로 상시 사용 |

> 요약: ARP는 정방향 매핑의 핵심, RARP는 DHCP에 흡수된 역방향, GARP는 상태 변경을 알리는 보조 수단으로 셋의 역할이 뚜렷이 갈림.

리스크·대응(불릿):
- ARP Spoofing(MITM) — 게이트웨이 IP에 자기 MAC을 묶어 가짜 Reply 지속 전송 — DHCP Snooping+DAI로 바인딩 불일치 ARP 차단.
- Broadcast Storm — 다수 단말 동시 요청으로 대역폭 마비 — VLAN 분할·서브네팅으로 브로드캐스트 도메인 축소.
- HA 절체 지연 — Active/Standby 전환 시 인접 스위치의 MAC 인지 지연 — 승격 즉시 GARP 강제 발송으로 캐시 갱신.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **DAI 기반 L2 통제**: DHCP Snooping 바인딩 테이블을 신뢰 기준으로 삼아, IP-MAC이 불일치하는 ARP 패킷을 스위치 단에서 즉시 Drop.
2. **VLAN 격리 설계**: 부서·층별로 VLAN을 나눠 단일 브로드캐스트 도메인에 다수 단말이 몰리지 않게 하여 ARP 폭주를 예방.
3. **핵심 자산 Static ARP**: DB 서버·망연계 게이트웨이 등은 OS에서 IP-MAC을 정적 고정해 위조 Reply를 원천 차단.

**결론(2줄):**
- 기술사 판단: 소규모 단일 세그먼트면 기본 ARP로 충분하나, 사용자·서버 혼재 기업망이면 DHCP Snooping+DAI 연계 접근 통제가 필요함.
- 향후 방향: SDN·클라우드에서는 컨트롤러가 브로드캐스트를 억제하고 매핑을 유니캐스트로 밀어넣는(Proxy ARP·컨트롤러 학습) 방식으로 진화 중이며, IPv6는 NDP로 대체됨.
