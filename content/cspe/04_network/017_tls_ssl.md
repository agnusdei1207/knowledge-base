## Ⅰ. 개요
- **정의**: 전송 계층 위에서 기밀성·무결성·인증을 제공하는 암호화 프로토콜
- **배경/필요성**: 인터넷 통신은 기본적으로 평문이므로 도청·변조·위장을 방지할 보안 계층이 필요함
- **비유**: 대화 전 상대방 신분증 확인(인증) 후 암호 언어로 대화(암호화)하는 과정과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 핸드셰이크 절차와 암호화 원리 | 인증서 검증, 키 교환, 대칭키 전환 | SSL은 폐기됨, TLS 1.2와 1.3의 핸드셰이크 라운드트립 차이 |

> 요약: 인증서 기반 인증과 대칭키 암호화로 전송 구간을 보호하는 보안 프로토콜임

## Ⅱ. 구성요소
```text
Application Data
       |
+------v-------+
| TLS Record   | -- 분할, 압축, MAC, 암호화
+------+-------+
| Handshake    | -- 인증, 키 교환
| ChangeCipher | -- 암호 전환 통보
| Alert        | -- 오류/종료 통보
+--------------+
       |
   TCP Layer
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Handshake Protocol | 인증서 교환, 키 합의를 수행하는 협상 프로토콜 | 대화 전 신분증 교환 |
| Record Protocol | 데이터를 분할·MAC·암호화하여 전송하는 계층 | 편지를 봉인·밀봉하는 과정 |
| 인증서 (X.509) | 서버(및 클라이언트) 신원을 CA가 보증하는 전자 문서 | 공인기관 발급 신분증 |
| 세션 키 | 핸드셰이크로 합의된 대칭 암호화 키 | 대화용 암호 코드북 |

> 요약: 핸드셰이크-레코드-인증서-세션키의 4요소로 보안 채널을 구성함

## Ⅲ. 절차
```text
Client                           Server
  |---ClientHello(버전,Cipher)---->|
  |<--ServerHello,Certificate------|
  |<--ServerKeyExchange,Done-------|
  |---ClientKeyExchange,Finished-->|
  |<--Finished---------------------|
  |===암호화된 Application Data====|
```
- 1단계: ClientHello로 지원 TLS 버전, 암호 스위트, 랜덤 값 전송
- 2단계: ServerHello로 선택된 암호 스위트 회신 및 서버 인증서 전송
- 3단계: 키 교환(ECDHE 등) 수행 후 양측이 동일한 세션 키 도출
- 4단계: Finished 메시지로 핸드셰이크 무결성 검증 후 암호화 통신 개시

> 요약: Hello교환-인증서전송-키합의-암호화개시의 4단계로 보안 채널을 수립함

## Ⅳ. 문제점
- 핸드셰이크 지연: TLS 1.2는 2-RTT가 소요됨 — 모바일·고지연 환경에서 초기 연결 시간 증가
- 인증서 관리 부담: 갱신 누락 시 서비스 중단이 발생함 — 수동 관리 시 만료일 추적이 어려움
- 레거시 프로토콜 잔존: SSL 3.0, TLS 1.0/1.1이 일부 시스템에 남아 있음 — 알려진 취약점(POODLE, BEAST)에 노출

> 요약: 핸드셰이크 비용, 인증서 운영, 레거시 취약점이 주요 과제임

## Ⅴ. 개선방안
1. 단기: TLS 1.3 전환으로 1-RTT(재연결 시 0-RTT) 핸드셰이크 달성
2. 중기: ACME 기반 인증서 자동 발급·갱신 체계 구축으로 운영 부담 제거
3. 장기: TLS 1.0/1.1 완전 비활성화 및 PQC(Post-Quantum Cryptography) 알고리즘 전환 준비

> 요약: TLS 1.3 전환, 자동화, PQC 대비의 단계적 보안 강화가 필요함

## Ⅵ. 전망
- 발전 방향: QUIC에 TLS 1.3이 내장되어 전송-보안 계층 통합이 가속화됨 (016 참조)
- 기술사적 판단: 양자 컴퓨팅 위협에 대비한 PQC 하이브리드 키 교환이 표준화 진행 중임
- 기술사 제언: 암호 스위트 선택·인증서 생명주기 관리를 포함한 TLS 거버넌스 체계 수립이 필요함
