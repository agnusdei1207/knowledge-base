# 📖 【암기용】 개념 완전 이해

> 목적: 애니캐스트 라우팅을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 동일한 IP 주소를 전 세계 여러 곳에 부여하고, 사용자가 접속하면 그중 '가장 가까운' 곳으로 연결해주는 통신 방식
- **왜 필요한가**: 구글(8.8.8.8)이나 클라우드플레어(1.1.1.1) 같은 큰 서비스가 미국에 한 대만 있다면 한국 사용자는 너무 느리다. 전 세계 수백 군데에 같은 주소의 서버를 두고 알아서 제일 가까운 곳을 찾아가게 함으로써 속도와 안정성을 동시에 잡기 위함이다.
- **핵심 직관**: 프랜차이즈 편의점 고객센터 번호는 하나지만, 내가 전화를 걸면 내 위치에서 가장 가까운 지점이나 상담원에게 연결되는 서비스와 같다.

## 깊이 이해
- **배경·문제의식**: 유니캐스트는 목적지가 하나라 그곳이 죽으면 끝이다. 멀티캐스트는 그룹 전체에 보내야 해서 복잡하다. 애니캐스트는 "누구든 좋으니 제일 가까운 놈이 대답해"라는 발상으로 가용성과 응답 속도를 극대화한다.
- **작동 원리**:
  - **IP 공유**: 여러 지리적 위치의 서버나 라우터에 동일한 IP 주소를 설정한다.
  - **BGP 라우팅**: 각 지점은 BGP(Border Gateway Protocol)를 통해 "내가 이 IP를 가지고 있다"라고 광고한다.
  - **최단 경로 선택**: 중간에 있는 라우터들은 BGP 경로 정보를 바탕으로 홉 수(Hop count)나 비용(Cost)이 가장 적은 최단 경로의 서버로 패킷을 전달한다.
- **비유**: 전 세계에 '도와줘요'라는 번호를 가진 대피소가 1,000개 있고, 내가 외치면 가장 근처에 있는 대피소 요원이 달려오는 시스템이다.
- **구체 예시**: 전 세계 13개뿐인 루트 DNS 서버(Root DNS Server)는 실제로는 애니캐스트를 통해 수천 개의 복제본(Mirror)으로 운영된다. 덕분에 어느 한 서버가 공격받아도 다른 서버가 대신 처리할 수 있다.
- **흔한 오해·주의점**: "애니캐스트가 로드 밸런싱인가?" 비슷하지만 다르다. 로드 밸런서(L4/L7)는 서버의 '부하'를 보고 나눠주지만, 애니캐스트는 네트워크의 '거리(라우팅 경로)'를 보고 나눠준다.

## 연결 개념
- **BGP (Border Gateway Protocol)**: 애니캐스트를 구현하기 위한 핵심 라우팅 프로토콜
- **CDN (Content Delivery Network)**: 애니캐스트를 활용하여 콘텐츠를 사용자 근처에서 전달하는 서비스
- **DDoS Mitigation**: 애니캐스트를 통해 공격 트래픽을 전 세계 여러 거점으로 분산시켜 흡수하는 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 애니캐스트의 1:1-of-N 메커니즘과 BGP 기반의 최단 경로 선정 원리, 그리고 이를 통한 서비스 가용성 및 지연 시간 단축 효과를 기술적으로 서술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 애니캐스트(Anycast)는 동일한 IP 주소를 다수의 노드에 할당하고, 네트워크 라우팅 메커니즘(BGP)에 의해 송신자로부터 가장 가까운 단일 노드로 패킷을 전달하는 방식이다.
> 2. **가치**: 지리적 근접성에 따른 응답 지연(Latency) 단축, 특정 노드 장애 시 자동 우회(Failover)를 통한 고가용성, 그리고 DDoS 공격 분산 효과를 제공한다.
> 3. **판단 포인트**: 상태 기반(Stateful) 서비스(TCP 등) 적용 시 경로 변경에 따른 세션 끊김 리스크를 고려하여 무상태(Stateless) 서비스(UDP, DNS) 위주로 우선 적용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 애니캐스트 통신 원리 및 특징 파악 | 1:Nearest(가장 가까운 노드), BGP 기반 경로 선정 | 단순히 "여러 곳에 보낸다"는 멀티캐스트와 혼동 |
| 가용성 및 보안 측면의 활용 사례 확인 | DNS 루트 서버, CDN, DDoS 분산 흡수(Sinkholing) | 기술적 메커니즘 없이 사례만 나열 |
| TCP 적용 시의 한계 및 고려사항 이해 | 세션 유지(Session Stickiness), 라우팅 플래핑 문제 | TCP 통신 시의 경로 변경 리스크 간과 |

> 요약: BGP의 AS-Path 정보를 활용한 최단 경로 탐색과 가용성 확보 및 공격 분산 효과를 부각함.

## Ⅰ. 개요 및 필요성

- 정의: 송신자가 보낸 패킷이 동일 주소를 가진 여러 수신 노드 중 라우팅 프로토콜 기준 최단 거리에 있는 하나에만 도달하는 전송 방식
- 배경: 글로벌 서비스의 응답 지연 시간(RTT) 단축 요구 및 특정 지역 대규모 장애/공격 시 서비스 연속성 확보 필요
- 필요성: 네트워크 홉 수 기반 자동 로드 분산, 무설정 자동 장애 복구(Self-healing), 대규모 DDoS 공격 트래픽 분산 수용

## Ⅱ. 구조 및 구성요소

```text
[애니캐스트 동작 구조]
            [Server A: 1.1.1.1] (Korea) <--- BGP Advertise
                     ^
                     | (Shortest Path for User 1)
User 1 (Korea) ----> [Internet Router] ----> [Server B: 1.1.1.1] (USA) <--- BGP Advertise
                               ^
                               | (Shortest Path for User 2)
User 2 (USA) ------------------+
```

| 구성요소 | 역할 및 특징 | 핵심 메커니즘 |
|:---|:---|:---|
| Shared IP | 여러 물리적 위치의 서버에 할당된 동일한 공인 IP 주소 | IPv4/IPv6 Anycast Address |
| BGP Routing | 동일 IP에 대한 여러 경로 정보를 인터넷 망에 전파 | AS-Path, Metric 경쟁 |
| Edge Router | 사용자와 가장 가까운 위치에서 최적 경로를 판단/전달 | BGP Best Path Selection |
| Anycast Node | 실제 서비스를 제공하는 복제된 서버 인프라 | DNS, CDN Edge, Scrubbing Center |

> 요약: 지리적으로 분산된 노드들이 동일 IP를 광고하면, 네트워크 라우팅 프로토콜이 사용자별 최적 노드를 결정함.

## Ⅲ. 동작원리 및 흐름도

```text
[애니캐스트 경로 선정 및 전송 흐름]
1. 노드 구성: 전 세계 거점(PoP) 서버에 8.8.8.8 동일 IP 설정
      |
2. 경로 광고: 각 거점 라우터가 BGP를 통해 8.8.8.8 도달 가능성 전파
      |
3. 경로 수렴: 중간 라우터들이 홉 수(AS-Path)가 가장 짧은 노드를 경로 테이블에 등록
      |
4. 패킷 전송: 사용자 패킷 도착 시 라우터가 자신의 테이블에 있는 '가장 가까운' 8.8.8.8로 전달
      |
5. 장애 복구: 특정 노드 장애 시 BGP 광고 중단 -> 라우터가 차순위(다음으로 가까운) 노드로 자동 경로 변경
```

| 단계 | 처리 내용 | 기술적 특징 |
|:---:|:---|:---|
| 1 | 동일 IP 주소를 가진 서버들을 지리적으로 분산 배치 | 가용성(Redundancy) 확보 |
| 2 | BGP Update 메시지를 통해 주변에 경로 정보 전파 | 라우팅 수렴 (Convergence) |
| 3 | 최단 AS-Path를 가진 노드를 목적지로 결정 | 네트워크 거리 기반 분산 |
| 4 | 패킷을 해당 노드로 포워딩 | 1:1-of-N 통신 |

> 요약: BGP의 자동 경로 수렴 기능을 활용하여 사용자에게 최단 거리의 서비스를 제공하고 장애를 우회함.

## Ⅳ. 특징

| 구분 | 유니캐스트 | 멀티캐스트 | 브로드캐스트 | 애니캐스트 |
|:---|:---:|:---:|:---:|:---:|
| 수신 대상 | 단일 지정 노드 | 그룹 내 전체 노드 | 동일 망 내 전체 노드 | **그룹 내 가장 가까운 노드** |
| 통신 비율 | 1 : 1 | 1 : N | 1 : All | **1 : 1-of-N** |
| 주요 용도 | 일반 웹, 메일 | 방송, 화상회의 | ARP, DHCP 탐색 | **DNS, CDN, DDoS 방어** |
| 가용성 | 노드 장애 시 단절 | 트리 재구성 필요 | 범위 내 동일 | **자동 Failover** |

> 요약: 애니캐스트는 유니캐스트의 목적지 식별성과 멀티캐스트의 분산성을 결합한 '최단 거리 전송' 기술임.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 유니캐스트 + GSLB | 애니캐스트 (Anycast) | 선택 기준 |
|:---|:---|:---|:---|
| 분산 기준 | DNS 응답(서버 부하 등) | 라우팅 경로 (네트워크 거리) | 분산 정책 |
| 복구 시간 | DNS TTL에 의존 (수 분) | BGP 수렴 속도 (수 초~수십 초) | 장애 복구 목표 (RTO) |
| 제어 정밀도 | 매우 높음 (사용자/지역별) | 낮음 (라우터 정책에 의존) | 제어 요구 수준 |

> 요약: 정밀한 부하 분산은 GSLB가 유리하나, 즉각적인 망 장애 대응과 네트워크 최적화는 애니캐스트가 우위임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| TCP 세션 끊김 | 라우팅 플래핑(Flapping)으로 경로 급변 시 | 무상태(Stateless) 서비스 우선 적용 | 세션 재연결 발생률 |
| 비대칭 경로 | 송신과 수신 경로가 서로 다른 노드 경유 | Connection Tracking 및 세션 동기화 | 비대칭 라우팅 비율 |
| 경로 편중 | 특정 노드로만 트래픽이 몰리는 현상 | BGP Community/Prepend로 경로 비용 조절 | 노드별 트래픽 편차 |

> 요약: TCP 기반 서비스 적용 시에는 경로 안정성을 확보하거나 세션 정보를 노드 간 공유하는 보완책이 필요함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 응답 속도 (RTT) | 글로벌 평균 50ms 이하 단축 | 전 세계 PoP별 Ping 테스트 |
| 장애 복구 시간 | 노드 다운 시 30초 이내 Failover | 모의 장애 테스트 및 BGP 수렴 확인 |
| 공격 분산율 | DDoS 공격 시 PoP별 분산 흡수율 | 트래픽 분석 툴 (NetFlow 등) |

> 요약: 전 세계적인 응답 속도 개선 효과와 장애 발생 시의 자동 복구 시간을 통해 성능을 평가함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **글로벌 DNS 인프라 고도화**: 8.8.8.8과 같은 공용 DNS 주소를 애니캐스트로 운영하여 전 세계 어디서든 10ms 이내의 빠른 질의 응답 제공
2. **DDoS 클린존(Scrubbing Center)**: 대규모 DDoS 공격 발생 시 애니캐스트를 통해 공격 트래픽을 여러 국가의 세척 센터로 분산시켜 전체 인프라 보호
3. **CDN 엣지 노드 최적화**: 정적 콘텐츠(이미지, JS 등)를 애니캐스트 기반 엣지 서버에서 제공하여 웹 페이지 로딩 속도 40% 이상 개선

**결론 (2줄):**
- 기술사 판단: 애니캐스트는 복잡한 하위 인프라를 하나의 IP로 추상화하여 가용성과 성능을 동시에 잡는 현대 인터넷의 필수 라우팅 전략임
- 향후 방향: IPv6 도입 확산과 함께 더 정교한 애니캐스트 주소 할당이 가능해져, 초저지연 모바일 서비스와 엣지 컴퓨팅의 근간이 될 것임
