# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 패킷의 목적지 IP 주소를 매번 확인하지 않고, 패킷 앞에 붙은 짧고 고정된 **레이블(Label)** 정보만 보고 패킷을 빠르게 전달하는 기술입니다.
- **필요성**: 기존의 IP 라우팅은 라우터마다 복잡한 주소를 일일이 검색해야 해서 느렸습니다. MPLS는 입구에서 딱 한 번만 검색하고, 그 뒤로는 번호표(레이블)만 보고 고속 질주하게 해줍니다.
- **핵심 직관**: **"고속도로 하이패스"**. 목적지 주소를 묻지 않고 차량 전면에 붙은 단말기(레이블) 정보만 보고 통과시키는 것과 같습니다.

## 깊이 이해
- **배경 (L2의 속도 + L3의 유연성)**: 2계층(스위칭)의 빠른 속도와 3계층(IP 라우팅)의 확장성을 결합했습니다. 그래서 흔히 **2.5계층 프로토콜**이라고 불립니다.
- **작동 원리 (Push, Swap, Pop)**:
  - **Push**: 입구 라우터(LER)가 패킷에 레이블을 붙입니다.
  - **Swap**: 중간 라우터(LSR)가 들어온 레이블을 다음 목적지용 레이블로 갈아 끼웁니다.
  - **Pop**: 출구 라우터(LER)가 레이블을 떼어내고 원래의 IP 패킷으로 되돌립니다.
- **FEC (Forwarding Equivalence Class)**: 동일한 경로로 처리될 패킷들의 그룹입니다. 같은 FEC에 속하면 같은 레이블을 받습니다.
- **비유 (택배 분류 시스템)**:
  - **IP 라우팅**: 매 정거장마다 상자 안의 송장 주소를 읽고 어디로 보낼지 결정함.
  - **MPLS**: 입구에서 상자 위에 "1번 라인"이라는 큰 스티커(레이블)를 붙임. 중간 관리자는 주소는 안 보고 스티커 번호만 보고 기계적으로 분류함.

## 연결 개념
- **MPLS VPN**: 레이블을 하나 더 붙여서(Stacking) 고객별 트래픽을 완벽하게 격리하는 기술. 기업 전용 회선의 표준입니다.
- **Traffic Engineering (TE)**: 정해진 최단 경로가 아니라, 여유 있는 우회로를 레이블로 강제 지정하여 전체 망 효율을 높이는 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: IP 헤더와 L2 헤더 사이에 32비트 심(Shim) 헤더를 삽입하여 목적지 IP 대신 고정 길이 레이블을 기반으로 포워딩하는 L2.5 기술임.
> 2. **가치**: 홉별 최장 일치 검색(LPM) 오버헤드를 제거하여 전송 속도를 높이고, VPN 및 트래픽 엔지니어링(TE)을 통해 망 운영 효율을 극대화함.
> 3. **판단 포인트**: 현대의 고속 ASIC 발달로 단순 속도 향상보다는 가상화(VPN)와 경로 강제(TE)를 통한 서비스 품질 차별화에 핵심 가치가 있음.

## Ⅰ. MPLS의 정의 및 계층적 위치
- **정의**: 네트워크 레이어(L3)의 주소 대신 레이블이라는 짧은 식별자를 사용하여 데이터를 전송하는 스위칭 기법.
- **계층적 위치 (L2.5)**: 데이터링크(L2)와 네트워크(L3) 계층 사이에 위치. `[L2 Header] - [MPLS Label] - [IP Header] - [Data]`

## Ⅱ. MPLS 심(Shim) 헤더 구조 (32bit)

| 필드명 | 비트수 | 설명 |
|:---:|:---:|:---|
| **Label** | 20 bit | 실제 스위칭에 사용되는 식별 번호 (0~2^20-1) |
| **Exp (TC)** | 3 bit | QoS(우선순위) 제어를 위한 필드 (Experimental) |
| **S (Stack)** | 1 bit | 레이블 스택의 바닥임을 표시 (1이면 마지막 레이블) |
| **TTL** | 8 bit | 루프 방지를 위한 생존 시간 필드 |

## Ⅲ. MPLS의 핵심 동작 프로세스 및 장비 역할

### 1. 주요 장비 구성
- **LER (Label Edge Router)**: MPLS 망의 입/출구. 레이블 삽입(Push) 및 제거(Pop) 수행.
- **LSR (Label Switch Router)**: MPLS 망의 내부. 레이블 교체(Swap) 및 포워딩 수행.

### 2. 동작 메커니즘 (LSP 형성)
1. **Label Distribution (LDP)**: 라우터끼리 목적지별 레이블 정보를 교환하여 경로(LSP)를 미리 생성.
2. **Ingress (Push)**: 패킷 유입 시 IP를 분석하여 레이블을 붙임.
3. **Transit (Swap)**: 레이블 테이블(LFIB)을 참조하여 레이블만 갈아 끼우며 전송.
4. **Egress (Pop)**: 레이블을 제거하고 원래의 IP 패킷을 다음 네트워크로 전달.

## Ⅳ. MPLS의 주요 응용 기술

### 1. MPLS VPN (L3 VPN)
- **원리**: 고객용 레이블과 전송용 레이블을 이중으로 겹침(Label Stacking).
- **장점**: BGP와 결합하여 고객별 독립적인 라우팅 공간(VRF) 제공. 사설 IP 중첩 허용.

### 2. MPLS TE (Traffic Engineering)
- **원리**: RSVP-TE 프로토콜을 사용하여 특정 경로에 대역폭을 예약하고 경로를 강제함.
- **장점**: 특정 링크로의 트래픽 쏠림 방지 및 가용 자원 최적 활용.

## Ⅴ. IP 라우팅 vs MPLS 스위칭 비교

| 비교 항목 | IP 라우팅 | MPLS 스위칭 |
|:---:|:---|:---|
| **검색 방식** | Longest Prefix Match (LPM) | Exact Match (Label) |
| **연산 부하** | 높음 (소프트웨어적 성격) | 낮음 (하드웨어적 스위칭) |
| **경로 결정** | 최단 경로 위주 (Shortest Path) | 정책 및 명시적 경로 (Explicit Path) |
| **주 용도** | 일반 인터넷 통신 | 기업 전용망, 백본 트래픽 제어 |

## Ⅵ. 기술사적 통찰: '단순화'에서 '서비스화'로
- **성능의 역설**: 과거에는 라우터 CPU 성능 한계를 극복하기 위해 MPLS를 썼으나, 현재는 ASIC의 발달로 IP 라우팅도 매우 빠름. 따라서 현재 MPLS의 존재 이유는 속도가 아니라 **"서비스의 유연성(VPN/TE)"**에 있음.
- **세그먼트 라우팅(SR)으로의 진화**: 복잡한 LDP 제어 프로토콜을 없애고, 소스 라우팅 개념을 도입하여 MPLS의 가치를 계승하면서도 구조를 단순화하는 방향으로 발전 중임.
- **결론**: MPLS는 전송 인프라의 가상화를 실현한 핵심 기술이며, 5G 및 멀티클라우드 환경에서 트래픽의 흐름을 정교하게 제어하는 **"네트워크의 혈관 제어기"**임.
