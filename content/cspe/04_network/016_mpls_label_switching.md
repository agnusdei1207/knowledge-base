# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: MPLS는 목적지 IP를 매 홉마다 검색하지 않고, 패킷 앞에 붙은 짧은 고정 레이블(Label)만 교체하며 전달하는 레이블 기반 고속 스위칭 기술임(L2와 L3 사이에서 동작해 2.5계층으로 불림).
- **왜 필요한가**: 순수 IP 라우팅은 홉마다 최장 일치(Longest Prefix Match) 검색을 반복해 느리고, 최적 경로 한 곳으로 트래픽이 몰리며, 고객별 트래픽 격리(VPN)나 경로 강제(TE)가 어려웠음.
- **핵심 직관**: 지하철 환승과 같음. 역마다 "부산 가려면 어디로?"(IP 검색)를 묻지 않고, 입구에서 "초록 노선(레이블)"만 배정받아 바닥 선을 따라 무뇌 고속 이동하는 것과 같음.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 표기는 답안 Ⅰ~Ⅵ에 그대로 등장하므로 비유와 함께 먼저 이해해 둠. 상위 핵심 키워드는 **레이블 스위칭(레이블만 보고 전달)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 레이블(Label, 20bit) | 패킷에 붙이는 고정 길이 숫자 꼬리표, 다음 홉을 지정 | 택배 바코드 — 주소 대신 스캔만 |
| 심(Shim) 헤더 32bit | L2 헤더와 L3(IP) 헤더 사이에 끼우는 MPLS 헤더 | 봉투와 편지 사이에 끼운 분류 스티커 |
| Exp/TC(3bit) | 우선순위(QoS) 표시 필드 | 택배의 "긴급" 도장 |
| S(1bit) | 레이블 스택 맨 아래(Bottom) 여부 표시 | 스티커 여러 장 중 맨 밑장 표시 |
| TTL(8bit) | 홉 제한(무한 루프 방지) | 유통기한 |
| Push / Swap / Pop | 레이블 삽입 / 교체 / 제거 동작 | 스티커 붙이기 / 바꿔붙이기 / 떼기 |
| LER(Edge Router) | 망 입구·출구 라우터, IP 검사 후 Push/Pop 수행 | 물류 접수·배달 창구 |
| LSR(Switch Router) | 망 내부 라우터, 레이블만 Swap 하며 전달 | 중간 물류센터의 바코드 릴레이 |
| FEC(Forwarding Equivalence Class) | 같은 방식으로 처리할 패킷 묶음(같은 레이블 부여 대상) | 같은 목적지 소포를 한 바구니로 묶음 |
| LSP(Label Switched Path) | 레이블로 미리 확립된 단방향 전송 경로 | 미리 그어둔 전용 노선 |
| LDP | 라우터끼리 레이블 매핑을 나눠 LSP를 만드는 제어 프로토콜 | 노선표를 서로 맞추는 회의 |
| LFIB | 레이블 전용 포워딩 테이블(하드웨어 처리) | 바코드 전용 분류 색인 |
| VRF | 라우터 하나에 고객별로 분리한 가상 라우팅 테이블 | 한 건물 안 세대별 우편함 |

## 깊이 이해
- **배경·문제의식**: IP 라우팅(계층 기본은 001·002 참조)은 홉마다 소프트웨어로 최장 일치 검색을 반복해 느렸고, ATM/프레임릴레이 같은 L2 고속 스위칭의 속도와 IP의 유연성을 결합할 기술이 필요했음.
- **작동 원리(어떻게+왜)**: 입구 LER이 IP를 한 번만 보고 FEC를 판별해 레이블을 Push함. 이후 내부 LSR은 IP를 아예 보지 않고 LFIB에서 레이블만 Swap 함 — 검색이 20bit 정확 일치(Exact Match)라 하드웨어(ASIC)로 초고속 처리되기 때문임. 출구 직전에서 Pop 하여 순수 IP로 복원함.
- **비유**: 우체국 택배 분류. 입구에서 바코드(레이블)를 붙이면 중간 물류센터(LSR)는 주소(IP)를 읽지 않고 스캐너로만 릴레이함.
- **구체 예시**: 통신사 백본에서 기업 A와 B가 똑같이 사설 대역 10.1.1.0/24를 써도, 서로 다른 VPN 레이블을 부여해 섞이지 않게 격리 전송함(MPLS VPN).
- **흔한 오해·주의점**: 요즘은 ASIC 발달로 "속도 향상" 자체는 의미가 줄었음. 그럼에도 트래픽 엔지니어링(경로 강제)과 L3/L2 VPN 구현 수단으로서 통신사 망의 사실상 표준임.

## 연결 개념
- MPLS VPN(L3 VPN·VRF+BGP, L2 VPN·VPLS)
- 트래픽 엔지니어링(MPLS TE, RSVP-TE, Fast Reroute)
- SRv6(Segment Routing over IPv6, MPLS 후속 단순화)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: L2 헤더와 L3(IP) 헤더 사이에 32bit 심(Shim) 헤더를 삽입해 레이블 기반 정확 일치(Exact Match) 스위칭을 수행하는 L2.5 기술임.
> 2. **가치**: 통신사 백본에서 고객별 트래픽 격리(VPN)와 명시적 경로 지정(Traffic Engineering)을 단일 물리망 위에서 제공함.
> 3. **판단 포인트**: IP의 복잡성과 ATM의 고정성을 결합한 L2.5 구조와 Push/Swap/Pop 메커니즘, LDP-IGP 동기화가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 라우팅 한계 극복과 통신사 백본 인프라 이해 | MPLS 헤더(Label·Exp·S·TTL) 구조, LER/LSR 역할 분담, FEC·LSP·LDP | "빠르다"만 서술·TE/VPN 목적 누락, 헤더 삽입 위치(L2.5) 누락 |

> 요약: MPLS 헤더 구조와 LSP 형성 과정을 서술하고, VPN·TE 응용을 함께 제시해야 함.

## Ⅰ. 개요 및 필요성
- 정의: IP 패킷에 고정 길이 레이블을 부여하고 라우터가 레이블 테이블만 참조해 고속 포워딩하는 L2.5 기술임.
- 배경: 순수 IP 라우팅의 홉 바이 홉 최장 일치 검색 오버헤드와 최적 경로 트래픽 집중 문제가 심화됨.
- 필요성: Ethernet·SONET 등 다양한 L2 매체 위에서 프로토콜 독립적으로 동작하며 QoS·TE·VPN을 통합 지원하는 전송 기반 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
패킷 구조: [L2 헤더] -> [MPLS Shim 32bit] -> [L3 IP 헤더] -> [Payload]
   MPLS Shim = Label(20) / Exp(3) / S(1) / TTL(8)

망 구조: IP망 -> Ingress LER -> LSR -> LSR -> Egress LER -> IP망
   제어: LDP/RSVP-TE 가 LER·LSR 간 레이블 분배 -> LSP 형성
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| LER(Edge Router) | 망 진입·진출점, IP 검사 후 Push/Pop 수행 | IP 라우팅 테이블(FIB) 참조 |
| LSR(Switch Router) | 내부 라우터, 레이블만 Swap 포워딩 | LFIB로 하드웨어 스위칭 |
| FEC | 같은 처리·경로로 묶는 패킷 분류 단위 | 하나의 FEC가 하나의 레이블에 매핑 |
| LDP | 레이블 바인딩 분배·LSP 형성 제어 프로토콜 | OSPF/IS-IS 등 IGP와 연동됨 |
| LSP | 레이블로 확립된 단방향 전송 경로 | 목적지 지향 가상 회선 |

> 요약: LER이 FEC를 판별해 레이블을 붙이면, 내부 LSR은 LFIB 기반 레이블 포워딩만 수행해 속도를 극대화함.

---

## Ⅲ. 동작원리 및 흐름도

```text
IP 패킷 유입 -> Ingress LER: FEC 판별 + Label Push -> LSR: Label Swap -> LSR: Label Swap
 -> Egress 직전 LSR: PHP(Label Pop) -> Egress LER: 순수 IP 포워딩 -> IP 패킷 유출
```

1. Ingress LER이 목적지 IP를 보고 FEC를 판별한 뒤 레이블을 삽입함(Push).
2. 내부 LSR이 LFIB에서 입력 레이블을 조회해 출력 레이블로 교체함(Swap), IP는 참조하지 않음.
3. Egress 직전 LSR이 레이블을 미리 제거함(PHP, Penultimate Hop Popping)해 Egress 부하를 줄임.
4. Egress LER이 순수 IP 패킷으로 외부 망에 포워딩함(Pop 완료).

> 요약: Ingress에서 Push, 코어에서 Swap, Egress 직전 PHP로 레이블을 떼어 Egress의 이중 검색 부하를 줄임.

---

## Ⅳ. 특징
- L2.5 위치: L2 헤더와 IP 헤더 사이에 삽입되어 Ethernet·PPP·SONET 등 하부 매체에 독립적으로 동작함.
- 정확 일치 스위칭: 20bit 레이블 Exact Match로 최장 일치 대비 검색 연산을 단순화해 ASIC 처리에 유리함.
- 레이블 스택: 레이블을 여러 겹 쌓아(S 비트로 최하단 표시) VPN·TE를 계층적으로 중첩 구현함.
- 경로 강제 가능: IGP 최단 경로를 무시하고 RSVP-TE로 명시적 우회 LSP를 지정함.
- 트래픽 격리: VPN 레이블로 중복 사설 IP 대역도 단일 물리망에서 분리 전송함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 전통적 IP 라우팅(L3) | MPLS 레이블 스위칭(L2.5) |
|:---|:---|:---|
| 검색 방식 | 목적지 IP 최장 일치(Longest Match) | 20bit 고정 레이블 정확 일치(Exact Match) |
| 경로 제어 | IGP Metric 단일 최적 경로 고정 | LDP/RSVP-TE 다중 터널·우회 경로 |
| 고객 분리 | GRE/IPsec 별도 터널 구성 필요 | VPN 레이블로 본원적 격리 지원 |

> 요약: 엔터프라이즈 내부는 IP 라우팅으로 충분하나, 대규모 고객 트래픽을 다루는 통신사 백본은 MPLS TE/VPN이 필수적임.

- 리스크: LDP-IGP 수렴 불일치로 인한 블랙홀 — 라우팅은 우회했으나 LSP 미형성 — LDP-IGP Synchronization 활성화로 대응함.
- 리스크: 단일 LSP 링크 단절 — 광케이블 단선 시 경로 소실 — MPLS FRR(Fast Reroute) 50ms 이내 절체로 대응함.
- 지표: 절체 지연 — 목표 50ms 이내 — 링크 다운 시각 대비 복구 시각 측정함.
- 지표: 패킷 손실률 — 목표 0%에 근접 — LDP 세션 상태·전송 카운터로 측정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. [기업 통신망] 전국망 기업이 통신사 MPLS L3 VPN(VRF+BGP)을 구독해, 사설 IP 변경 없이 지사 간 격리 터널 확보(IPsec 암호화 오버헤드 절감).
2. [장애 복구] 코어 LSR 간 RSVP-TE 기반 MPLS FRR 터널을 사전 구성해, 링크 다운 시 50ms 이내 우회 절체.
3. [망 분리] 클라우드 접속용 VRF와 내부 행정망 VRF를 단일 물리 라우터에서 MPLS VPN으로 논리 분리 구성.

**결론(2줄):**
- 기술사 판단: ASIC 발달로 IP 라우팅도 선속도(Line-rate)를 지원하나, 트래픽 엔지니어링 요구가 크면 MPLS TE, 대체 불가한 고객 격리가 필요하면 MPLS VPN을 선택함.
- 향후 방향: 클라우드 네이티브 환경에서는 복잡한 LDP 대신 IPv6 헤더를 확장 활용하는 SRv6로 백본이 단순화·진화 중임.
