## 미리 알고가기

- MPLS: IP 패킷 앞에 짧은 레이블을 붙여 레이블 스위칭 경로로 전달하는 기술임
- LER: MPLS 망의 입구와 출구에서 IP 패킷과 레이블을 붙이거나 제거하는 라우터임
- LSR: MPLS 망 내부에서 레이블을 바꿔 다음 홉으로 넘기는 라우터임
- LSP: 레이블이 붙은 패킷이 MPLS 망을 따라 이동하는 논리 경로임
- FEC: 같은 전달 처리를 받을 패킷 묶음이며 입구 라우터가 분류함

## Ⅰ. 개요

- **정의/개념**: MPLS는 입구 라우터가 패킷을 FEC로 분류해 레이블을 붙이고 내부 라우터가 레이블만 교체하며 전달하는 경로 제어 기술임
- **배경/필요성**: 백본망과 전용망에서는 단순 목적지 IP 기반 전달만으로 서비스 분리, 트래픽 엔지니어링, 우회 경로 제어를 설명하기 어려워 레이블 기반 경로가 필요함

## Ⅱ. 특징

- MPLS 내부 라우터는 긴 IP 프리픽스 조회 대신 레이블 값으로 다음 동작을 결정함
- LSP를 미리 구성하면 특정 서비스나 고객 트래픽을 지정 경로로 보낼 수 있음
- VPN, Traffic Engineering, Fast Reroute처럼 서비스별 경로 제어에 활용됨
- 레이블 분배와 경로 설계가 틀리면 특정 VPN이나 서비스만 단절될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | IP 라우팅 | MPLS |
|:---|:---|:---|
| 전달 기준 | 목적지 IP 프리픽스를 조회함 | 레이블 값을 보고 다음 홉과 동작을 정함 |
| 경로 제어 | 라우팅 프로토콜의 최적 경로를 주로 따름 | LSP로 서비스별 경로를 명시하거나 제어함 |
| 서비스 분리 | VRF나 ACL 등 별도 구조가 필요함 | L3VPN, L2VPN처럼 레이블로 고객 트래픽을 분리함 |
| 운영 쟁점 | 라우팅 테이블과 다음 홉 도달성을 확인함 | 레이블 분배, LSP 상태, VRF 매핑을 함께 확인함 |

> 요약: MPLS는 목적지 IP만 보는 전달을 레이블 기반 서비스 경로 제어로 확장함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Ingress LER | IP 패킷을 FEC로 분류하고 최초 레이블을 붙여 MPLS 망으로 넣음 |
| LSR | 입력 레이블을 출력 레이블로 바꾸고 다음 홉으로 전달함 |
| Egress LER | 마지막 레이블을 제거하고 원래 IP 패킷으로 외부망에 전달함 |
| Label Forwarding Table | 입력 레이블, 출력 레이블, 다음 홉 동작을 저장한 테이블임 |
| Control Plane | LDP, RSVP-TE, BGP 등으로 레이블과 경로 정보를 배포함 |

```text
+----------+     +-----+     +-----+     +----------+
| Ingress  | --> | LSR | --> | LSR | --> | Egress   |
| Push     |     |Swap |     |Swap |     | Pop      |
+----------+     +-----+     +-----+     +----------+
```

> 요약: MPLS 구조는 입구에서 붙이고, 중간에서 바꾸고, 출구에서 제거하는 레이블 처리로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| FEC분류   | --> | LabelPush| --> | LabelSwap| --> | LabelPop |
+----------+     +----------+     +----------+     +----------+
```

1. **FEC분류**: Ingress LER가 목적지, VPN, QoS 기준으로 패킷을 분류함
2. **LabelPush**: 분류 결과에 맞는 레이블을 붙여 MPLS 망으로 보냄
3. **LabelSwap**: LSR이 입력 레이블을 출력 레이블로 교체해 LSP를 따라 전달함
4. **LabelPop**: Egress LER가 레이블을 제거하고 IP 패킷으로 내보냄

## Ⅵ. 실무 적용 및 유의점

1. 통신사 백본의 L3VPN에서는 고객별 VRF와 레이블 매핑이 맞아야 하므로 RD/RT, LFIB, VPN 라우팅 테이블을 함께 확인해 고객 간 경로 혼선을 막음
2. Traffic Engineering을 적용할 때는 지정 LSP가 실제 혼잡 회선을 우회하는지 확인해야 하며 링크 사용률, LSP 상태, Fast Reroute 전환 시간으로 검증함

## Ⅶ. 결론

MPLS는 전달 속도 표현보다 FEC 분류, 레이블 교체, LSP 제어로 서비스별 경로를 운영하는 기술로 설명해야 함.

## 작성 근거(검토용)

- MPLS의 과거 설명은 빠른 스위칭으로 흐르기 쉬우나 현대 답안에서는 VPN, TE, FRR 같은 경로 제어가 판단 기준이므로 그 축으로 구성함
- 서비스 품질은 LSP 상태, 링크 사용률, 전환 시간처럼 검증 가능한 표현으로 바꿈
- 결론은 속도보다 레이블 절차와 서비스 경로 제어를 회수함
