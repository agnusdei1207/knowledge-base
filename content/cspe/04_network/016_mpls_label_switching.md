## 미리 알고가기

- FEC: 같은 전달 정책을 적용할 패킷 묶음임
- LER: MPLS 망의 입구와 출구에서 레이블을 붙이거나 떼는 장비임
- LSR: MPLS 망 내부에서 레이블만 바꿔 전달하는 장비임
- LSP: 레이블을 따라 패킷이 지나가는 논리 경로임

## Ⅰ. 개요

- **정의/개념**: MPLS는 패킷의 목적지 IP를 홉마다 다시 계산하지 않고, 입구에서 붙인 짧은 레이블을 기준으로 전달하는 스위칭 방식임. 2계층 스위칭의 단순한 전달 방식과 3계층의 경로 제어를 함께 활용하기 위해 쓰는 구조로 봄
- **배경/필요성**: 백본망과 기업 전용망에서는 단순 최단 경로보다 서비스별 우회 경로, 고객별 분리, 품질 보장이 더 중요하므로 레이블 기반 전달 구조가 필요함

## Ⅱ. 특징

- 패킷을 FEC로 묶어 한 번 분류한 뒤에는 레이블만 보고 전달하므로 경로 정책을 일관되게 적용하기 쉬움
- 레이블 스택을 사용하면 전송 경로와 고객 식별을 분리할 수 있어 MPLS VPN 구성이 자연스러움
- 최단 경로만 따르지 않고 운영자가 지정한 경로로 트래픽을 보낼 수 있어 트래픽 엔지니어링에 유리함
- 단순 전달 속도보다 경로 제어, 품질 보장, 서비스 분리가 MPLS의 실질적 가치임

## Ⅲ. 종류 및 비교

| 판단 기준 | IP 라우팅 | MPLS |
|:---|:---|:---|
| 전달 기준 | 각 홉이 목적지 IP를 보고 다음 경로를 다시 계산함 | 입구에서 붙인 레이블을 기준으로 다음 홉을 결정함 |
| 경로 선택 | 라우팅 프로토콜이 계산한 최단 경로 의존성이 큼 | 운영 정책에 따라 명시적 경로나 우회 경로를 강제하기 쉬움 |
| 서비스 분리 | VRF나 터널을 별도로 설계해야 함 | 레이블 스택으로 고객 망과 전송 경로를 함께 분리하기 쉬움 |
| 대표 활용 | 일반 인터넷 라우팅에 적합함 | 백본망, 기업 전용망, 트래픽 엔지니어링에 적합함 |

> 요약: MPLS는 IP 전달을 대체한다기보다, 경로 제어와 서비스 분리를 더 정교하게 만들기 위해 덧붙이는 구조임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| LER | 패킷이 MPLS 망에 들어올 때 FEC를 판단해 레이블을 붙이고, 나갈 때는 레이블을 제거함 |
| LSR | 내부 경로에서 들어온 레이블을 다음 구간용 레이블로 바꿔 전달하므로 고속 포워딩의 중심이 됨 |
| LFIB | 레이블과 출력 인터페이스의 대응 관계를 저장하는 전달 테이블이며, 이 정보가 정확해야 스위칭이 꼬이지 않음 |
| LSP | 패킷이 실제로 지나가는 논리 경로이며, 트래픽 엔지니어링과 장애 우회 정책이 이 경로 위에서 동작함 |

```text
+--------+     +--------+     +--------+     +--------+
| Ingress| --> |  LSR   | --> |  LSR   | --> | Egress |
|  LER   |     |        |     |        |     |  LER   |
+--------+     +--------+     +--------+     +--------+
    |               |              |              |
    +-- Push -------+-- Swap ------+-- Swap ------+-- Pop
```

> 요약: MPLS 구조의 핵심은 입구에서 분류하고, 중간에서는 레이블만 바꾸고, 출구에서 원래 패킷으로 돌려보내는 데 있음

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| FEC분류  | --> | Label부여 | --> | Label교환 | --> | Label제거 |
+----------+     +----------+     +----------+     +----------+
```

1. **FEC분류**: 입구 LER가 패킷 목적지와 서비스 정책을 보고 어떤 FEC에 넣을지 결정함
2. **Label부여**: 선택한 FEC에 맞는 레이블을 붙여 MPLS 망으로 보냄
3. **Label교환**: 내부 LSR가 LFIB를 참조해 레이블을 다음 구간 값으로 바꾸며 전달함
4. **Label제거**: 출구 LER가 레이블을 제거하고 일반 IP 패킷으로 다음 구간에 넘김

## Ⅵ. 실무 적용 및 유의점

1. 기업 전용망에서는 MPLS VPN으로 고객별 트래픽을 분리하되 VRF와 레이블 매핑이 어긋나면 다른 망으로 잘못 전달될 수 있으므로 라우팅 인스턴스와 레이블 테이블을 함께 점검하고 VPN 경로 누수 건수와 지연 시간으로 확인함
2. 백본망에서는 MPLS TE로 혼잡 링크를 우회할 수 있지만 경로를 과도하게 고정하면 장애 시 우회 여지가 줄어드므로 예비 경로와 대역폭 예약을 함께 설계하고 링크 사용률과 LSP 절체 시간을 기준으로 확인함

## Ⅶ. 결론

MPLS는 단순 전달 속도를 높이기 위한 기술이 아니라, 백본망과 전용망에서 경로와 서비스를 원하는 방식으로 통제하기 위한 레이블 기반 전달 구조임.
