## Ⅰ. 개요
- **정의**: 네트워크 패킷의 IP 헤더를 검사하는 대신, 짧고 고정된 길이의 '라벨(Label)'을 붙여 고속으로 스위칭/포워딩하는 기술임.
- **배경/필요성**: 과거 IP 라우팅의 느린 소프트웨어 조회 속도 극복 목적과 다양한 프로토콜(ATM, Frame Relay, IP)을 단일 백본으로 통합 수용할 필요.
- **출제 의도**: 라벨 스위칭의 동작 원리(Push/Swap/Pop), 트래픽 엔지니어링(TE) 장점 및 기존 IP 라우팅과의 차이 이해.

## Ⅱ. 구성요소
```text
+------------------------------------------------+
|                MPLS Backbone Network           |
|                                                |
|  [IP Packet] -> [ LER 1 ] -> [ LSR ] -> [ LER 2] -> [IP Packet]
|                 (Push)       (Swap)     (Pop)  |
+------------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| LER (Label Edge Rtr) | 망 경계에 위치하며 외부 IP 패킷에 라벨을 붙이거나(Push) 떼어내는(Pop) 장비 | 택배 터미널 분류기 |
| LSR (Label Switch Rtr)| 망 내부에 위치하며 라벨만 보고 패킷을 다음 경로로 스위칭(Swap)하는 핵심 장비 | 고속도로 환승 센터 |
| Label & FEC | 패킷을 동일한 경로/품질로 처리하기 위한 짧은 식별자(Label)와 분류 기준(FEC) | 화물 목적지 바코드 |
> 요약: 망에 들어올 때 복잡한 IP 대신 바코드(Label)를 붙이고, 내부에서는 바코드만 보고 초고속으로 전송함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 패킷 인입 |-> | 라벨 삽입   |-> | 라벨 스위칭 |-> | 라벨 제거 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **패킷 인입**: 일반 사용자의 IP 패킷이 통신사/기업망의 MPLS 경계 라우터(LER)에 도착함.
2. **라벨 삽입(Push)**: LER이 패킷의 목적지와 서비스 등급(FEC)을 확인한 후 L2 프레임과 L3 IP 헤더 사이에 32비트 라벨을 삽입함.
3. **라벨 스위칭(Swap)**: 내부의 LSR들은 라우팅 테이블 조회를 생략하고, 라벨 테이블(LFIB)만 매핑하여 라벨을 교체하며 고속 전송함.
4. **라벨 제거(Pop)**: 최종 목적지 인근의 LER에서 라벨을 제거하고 순수 IP 패킷 형태로 타겟 네트워크에 전달함.
> 요약: 진입점(Push) - 경유지(Swap) - 목적지(Pop) 순서로 라벨 기반 터널링과 포워딩이 이루어짐.

## Ⅳ. 문제점
- **높은 회선 비용**: 기업이 지사 간 연결을 위해 통신사 MPLS 전용망을 임대할 경우 비용이 매우 고가임.
- **유연성 부족**: 장비 설정과 프로비저닝이 복잡하여 클라우드 환경 등 동적인 네트워크 변화에 신속하게 대응하기 어려움.
- **종단 간 암호화 부재**: MPLS 자체는 경로 격리(VPN)를 제공하지만 데이터 페이로드 암호화 기능이 없어 보안성 한계 존재.

## Ⅴ. 개선방안
- **트래픽 엔지니어링**: MPLS-TE(Traffic Engineering)를 활용해 특정 링크 편중을 막고 부하를 우회/분산하여 회선 효율 향상 (단기).
- **SD-WAN 병행 사용**: 중요 트래픽만 MPLS로 보내고 일반 트래픽은 저렴한 인터넷/IPsec 튜널로 분산하는 하이브리드 WAN 구축 (중기).
- **세그먼트 라우팅 진화**: 복잡한 라벨 분배 프로토콜(LDP/RSVP)을 제거하고 IGP/SDN 컨트롤러 기반으로 경로를 제어하는 Segment Routing(SR) 전환 (장기).

## Ⅵ. 전망
- 순수 고속 스위칭 목적의 의미는 퇴색되었으나, 통신사 백본의 트래픽 엔지니어링 및 BGP IP-VPN 구현을 위한 기반 기술로 계속 사용됨.
- 향후 기업망에서는 SD-WAN에 밀려 비중이 축소되고, 코어망에서는 IPv6 기반의 SRv6 아키텍처로 점진적 마이그레이션이 이루어질 것임.
