## 미리 알고가기

- S-NSSAI는 단말이 접속 시 요청하는 단일 슬라이스 식별자임
- SST는 서비스 유형을 나타내고 SD는 같은 유형 안에서 세부 슬라이스를 구분하는 값임
- NSI는 실제로 동작하는 종단 간 슬라이스 인스턴스임
- NSSI는 RAN, 전송, 코어처럼 영역별로 나뉜 슬라이스 부분 인스턴스임

## Ⅰ. 개요

- **정의/개념**: NSSAI, NSI, NSSI는 5G 슬라이싱 환경에서 단말이 원하는 슬라이스를 식별하고, 네트워크가 이를 실제 슬라이스 인스턴스로 연결하며, 영역별 하위 구성으로 조립하기 위한 표준 체계임
- **배경/필요성**: 슬라이스가 많아질수록 단말 요청, 실제 인스턴스, 구간별 구성 정보를 한 이름으로 처리하면 운영과 자동화가 꼬이므로, 요청 정보와 실행 인스턴스를 구분하는 계층적 식별 체계가 필요함

## Ⅱ. 특징

- 단말이 제시하는 요청 정보와 네트워크가 실제로 할당하는 인스턴스를 분리해 관리함
- 서비스 유형과 테넌트 구분 정보를 함께 담아 대량 슬라이스 운영에 적합함
- 하나의 NSI를 여러 NSSI 조합으로 구성할 수 있어 자원 재사용과 자동화에 유리함
- 슬라이스 생성, 변경, 종료를 오케스트레이터가 제어할 수 있도록 표준화된 관리 단위를 제공함

## Ⅲ. 종류 및 비교

| 판단 기준 | S-NSSAI와 NSSAI | NSI | NSSI |
|:---|:---|:---|:---|
| 주된 역할 | 단말이 어떤 슬라이스를 원한다고 요청할 때 쓰는 식별 정보임 | 실제로 서비스가 붙는 종단 간 슬라이스 인스턴스임 | NSI를 이루는 영역별 하위 인스턴스임 |
| 포함 정보 | SST와 SD를 조합해 서비스 유형과 세부 구분을 나타냄 | 자원, 정책, 기능 조합이 반영된 실행 단위임 | RAN, 전송, 코어 같은 구간별 구성 정보를 가짐 |
| 사용 시점 | 접속과 선택 단계에서 먼저 사용됨 | 할당과 운영 단계에서 사용됨 | 설계와 조립, 재사용 단계에서 중요함 |
| 운영 관점 | 가입 정책과 요청 해석이 핵심임 | SLA와 서비스 제공이 핵심임 | 자원 공유와 오케스트레이션 효율이 핵심임 |

> 요약: S-NSSAI는 요청 이름표이고 NSI는 실제 슬라이스이며 NSSI는 그 슬라이스를 이루는 부품 단위임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단말과 가입 정보 | 단말이 허용된 S-NSSAI 목록 안에서 원하는 슬라이스를 요청하는 시작점임 |
| AMF와 NSSF | 접속 절차에서 단말 요청과 가입 정책을 비교해 적합한 슬라이스를 선택하는 기능임 |
| NSI | 실제 사용자 트래픽과 정책이 적용되는 종단 간 슬라이스 실체임 |
| NSSI | NSI를 만들기 위해 RAN, 전송, 코어별로 나눠 관리하는 하위 단위임 |
| 관리 오케스트레이터 | NSI와 NSSI의 생성, 연결, 확장, 종료를 자동화하는 관리 계층임 |

```text
+-------------+     +----------------+     +----------------+     +----------------+
| 단말의 S-NSSAI | --> | AMF/NSSF 선택     | --> | NSI 할당          | --> | NSSI 조합         |
+-------------+     +----------------+     +----------------+     +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +----------------+
| 요청 정보 전달 | --> | 가입 정책 확인    | --> | NSI 선택·생성      | --> | NSSI 매핑·운영    |
+-------------+     +----------------+     +------------------+     +----------------+
```

1. **요청 정보 전달**: 단말이 접속 시 허용된 S-NSSAI를 제시함
2. **가입 정책 확인**: 네트워크가 단말 가입 정보와 서비스 정책을 바탕으로 요청 가능 여부를 판단함
3. **NSI 선택 또는 생성**: 적합한 슬라이스 인스턴스를 연결하거나 필요하면 새로 준비함
4. **NSSI 매핑과 운영**: 영역별 하위 인스턴스를 조합해 종단 간 슬라이스를 구성하고 품질을 관리함

## Ⅵ. 실무 적용 및 유의점

1. 같은 URLLC 유형 안에서도 여러 기업 전용 슬라이스를 운영하는 환경에서는 SST만 보고 처리하면 잘못된 테넌트에 연결될 수 있으므로 SD와 가입 정책 매핑을 엄격히 관리하고 슬라이스 오선택 건수와 접속 실패율로 확인함
2. 슬라이스 자동화 플랫폼을 운영할 때는 NSI 생성 속도보다 NSSI 재사용 기준이 더 중요하므로 구간별 하위 인스턴스 표준을 먼저 정하고 슬라이스 프로비저닝 시간과 하위 인스턴스 재사용률로 확인함

## Ⅶ. 결론

NSSAI, NSI, NSSI 체계의 핵심은 단말 요청과 실제 슬라이스 실체를 구분해 자동화 가능한 관리 단위로 만드는 데 있으므로 식별자 설계와 정책 매핑이 정확해야 함.
