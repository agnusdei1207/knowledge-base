## Ⅰ. 개요
- **정의**: 제어부와 데이터부를 분리하여 네트워크를 소프트웨어 기반으로 중앙 집중 제어하는 기술임.
- **배경/필요성**: 기존 하드웨어 장비 종속성 탈피, 클라우드 및 가상화 환경에 맞는 동적 네트워크 구성 요구 증가.
- **출제 의도**: SDN의 아키텍처 이해, NFV와의 연관성 및 기존 네트워크 대비 장단점 파악.

## Ⅱ. 구성요소
```text
+-------------------------------------------------+
|               Application Layer                 |
|             (Business/Network Apps)             |
+-------------------------------------------------+
                        | Northbound API (REST)
+-------------------------------------------------+
|                 Control Layer                   |
|                (SDN Controller)                 |
+-------------------------------------------------+
                        | Southbound API (OpenFlow)
+-------------------------------------------------+
|             Infrastructure Layer                |
|             (Data Plane, Switches)              |
+-------------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Application | 네트워크 서비스를 정의하고 제어 계층에 요청함 | 기업 경영진 |
| Controller | 네트워크 토폴로지 관리 및 제어 명령(Rule) 생성/하달 | 중앙 통제실 |
| Infrastructure | 컨트롤러의 명령에 따라 실제 트래픽 포워딩 처리 수행 | 도로망/신호등 |
> 요약: SDN은 애플리케이션, 컨트롤러, 인프라스트럭처의 3계층 구조로 중앙 제어를 실현함.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 앱 요구   |-> | 정책 변환   |-> | 룰(Rule)전송|-> | 패킷 처리 |
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **앱 요구**: 애플리케이션 계층에서 새로운 네트워크 서비스나 트래픽 경로 변경을 컨트롤러에 요청함.
2. **정책 변환**: 컨트롤러가 수신한 요구사항을 분석하여 물리 네트워크에 적용할 라우팅 정책으로 변환함.
3. **룰 전송**: Southbound API를 통해 컨트롤러가 하위 스위치 등에 패킷 처리 규칙(Flow Table)을 전송함.
4. **패킷 처리**: 데이터 평면의 장비들이 수신한 규칙을 기반으로 트래픽을 포워딩, 변조 또는 폐기함.
> 요약: 상위 계층의 비즈니스 논리가 중앙 컨트롤러를 거쳐 인프라의 포워딩 규칙으로 적용됨.

## Ⅳ. 문제점
- **단일 장애점(SPOF) 위험**: 컨트롤러 장애 시 전체 네트워크 제어 기능이 마비됨.
- **표준화 파편화**: Northbound API의 범용 표준 부재로 벤더 종속성 발생 가능.
- **컨트롤러 병목**: 대규모 네트워크나 빈번한 트래픽 변경 시 컨트롤러에 부하 집중.

## Ⅴ. 개선방안
- **단일 장애점 극복**: 컨트롤러 다중화(Active-Standby, 클러스터링) 아키텍처 적용 (단기).
- **개방형 생태계 구축**: ONOS, OpenDaylight 등 오픈소스 기반 사실상 표준(De-facto) 활용 (중기).
- **분산 제어 구조 적용**: 계층적 컨트롤러 구조 및 인텐트 기반 네트워크(IBN)로의 진화 (장기).

## Ⅵ. 전망
- 5G 에지 컴퓨팅 및 클라우드 인프라와 결합하여 동적 슬라이싱 기술의 핵심으로 작용할 것임.
- AI/ML이 융합된 무인 자동화 기반의 제로 터치 프로비저닝(Zero Touch Provisioning)으로 발전 예정임.
