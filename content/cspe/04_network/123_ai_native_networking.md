## 미리 알고가기

- 텔레메트리는 장비 상태와 트래픽과 지연 같은 운영 데이터를 지속적으로 보내는 방식임
- 폐루프 제어는 상태를 보고 바로 조정하고 다시 결과를 확인하는 제어 구조임
- 드리프트는 모델 성능이 실제 환경 변화로 서서히 떨어지는 현상임
- 롤백은 적용한 설정을 이전 상태로 되돌리는 절차임

## Ⅰ. 개요

- **정의/개념**: AI 네이티브 네트워킹은 네트워크 설계와 운영과 장애 대응에 AI 모델을 기본 제어 요소로 넣어 분석과 판단과 조정을 자동으로 반복하는 운영 방식임
- **배경/필요성**: 서비스 수와 경로 수와 설정 변화가 급격히 늘면서 규칙 기반 자동화만으로는 이상 징후와 최적 경로를 제때 다루기 어려워져, 운영 데이터를 학습해 스스로 조정하는 접근이 필요해짐

## Ⅱ. 특징

- 정적 규칙보다 실제 운영 데이터를 바탕으로 이상 징후와 수요 변화를 다룸
- 추천만 하는 수준에서 자동 조치까지 발전할 수 있음
- 결과 품질은 데이터 품질과 피드백 구조에 크게 좌우됨
- 잘못 학습한 모델이 운영망에 바로 반영되면 장애를 키울 수 있어 통제 장치가 필수임

## Ⅲ. 종류 및 비교

| 판단 기준 | 규칙 기반 자동화 | AI 네이티브 네트워킹 |
|:---|:---|:---|
| 판단 방식 | 사람이 정의한 조건으로 동작함 | 운영 데이터를 학습해 패턴을 추론함 |
| 변화 대응 | 새 상황마다 규칙 수정이 필요함 | 반복 데이터를 바탕으로 적응 폭을 넓힐 수 있음 |
| 설명 가능성 | 동작 이유가 비교적 명확함 | 모델 판단 근거 해석이 더 어려울 수 있음 |
| 적합 환경 | 단순 반복 작업에 적합함 | 복잡한 이상 탐지와 예측 최적화에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 텔레메트리 수집기 | 장비 상태와 트래픽 데이터를 모음 |
| 데이터 저장소 | 학습과 추론에 필요한 이력을 보관함 |
| AI 모델 | 이상 탐지와 예측과 추천을 수행함 |
| 정책 엔진 | 모델 결과를 적용 가능한 정책으로 바꿈 |
| 오케스트레이터 | 설정 반영과 롤백을 실행함 |

```text
+--------------+    수집    +-------------+    추론    +-------------+    반영    +-------------+
| 네트워크 데이터 | ------> | 데이터 저장소   | ------> | AI 모델        | ------> | 정책·자동화 계층 |
+--------------+          +-------------+          +-------------+          +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[데이터 수집] -> [모델 추론] -> [정책 결정] -> [적용] -> [결과 피드백]
```

1. **데이터 수집**: 트래픽과 지연과 장애 이력을 모음
2. **모델 추론**: 이상 징후나 혼잡 예측 결과를 계산함
3. **정책 결정**: 경로 변경이나 자원 확장 같은 조치를 정함
4. **적용**: 오케스트레이터가 설정을 반영함
5. **결과 피드백**: 성능 변화를 다시 학습 데이터로 돌림

## Ⅵ. 실무 적용 및 유의점

1. 처음부터 전체 운영망을 자동 제어하기보다 용량 예측이나 이상 징후 분류처럼 위험이 낮은 영역부터 시작하고 예측 오차와 경보 적중률과 수동 롤백 건수를 같이 보며 범위를 넓혀야 함
2. 모델이 오래되면 실제 트래픽과 어긋날 수 있으므로 주기적 재학습과 승인 기반 반영 절차를 함께 두고 드리프트 지표와 변경 후 장애 건수를 지속적으로 확인해야 함

## Ⅶ. 결론

AI 네이티브 네트워킹의 핵심은 자동화 기능을 더하는 데 있지 않고 운영 데이터를 바탕으로 판단과 조정을 반복하는 제어 구조를 만드는 데 있음.
