## Ⅰ. 개요
- 정의: 5G 코어 네트워크의 제어 평면 기능들을 서비스 형태로 모듈화하여 제공하는 클라우드 네이티브 기반 아키텍처임.
- 배경/필요성: 기존의 점대점(Point-to-Point) 연결 구조의 복잡성 해소 및 유연한 서비스 확장성 확보 필요.
- 출제 의도: SBA의 특징 이해 및 클라우드 환경에서의 5G 코어 진화 방향 파악.

## Ⅱ. 구성요소
```text
+-------------------+ +-------------------+
|      AMF          | |      SMF          |
+--------+----------+ +--------+----------+
         |                     |
+--------+---------------------+----------+
|       Service Based Interface (SBI)     |
+--------+---------------------+----------+
         |                     |
+--------+----------+ +--------+----------+
|      NRF          | |      UPF          |
+-------------------+ +-------------------+
```
- 구성요소 | 설명 | 비유
  - NRF | 서비스 등록/검색 기능 제공 | 주소록
  - AMF | 이동성 및 접속 관리 기능 | 안내데스크
  - SMF | 세션 관리 및 IP 할당 기능 | 배차 관리자
> 요약: SBA는 다양한 네트워크 기능(NF)을 서비스화하여 SBI를 통해 연동함.

## Ⅲ. 절차
```text
+----------------+      +----------------+      +----------------+
|  1.서비스 등록 | ---> |  2.서비스 검색 | ---> |  3.서비스 요청 |
+----------------+      +----------------+      +----------------+
```
- 1단계 (서비스 등록): 생성된 NF가 자신의 서비스를 NRF에 등록함.
- 2단계 (서비스 검색): 다른 NF가 필요한 서비스를 찾기 위해 NRF에 질의함.
- 3단계 (서비스 요청): 검색된 NF로 직접 서비스 요청 메시지를 전송함.
- 4단계 (응답 및 처리): 요청받은 NF가 서비스를 처리 후 결과를 반환함.
> 요약: 서비스 등록, 검색, 요청, 처리 순으로 네트워크 기능 간 상호작용이 이루어짐.

## Ⅳ. 문제점
- 1. 보안 위협 증가: 개방형 API 기반 구조로 인해 외부 공격 및 인가되지 않은 접근 위험이 존재함.
- 2. 네트워크 지연 발생: 중앙 집중형 SBI 라우팅으로 인한 트래픽 병목 및 처리 지연 가능성 존재.

## Ⅴ. 개선방안
- 1. 보안 강화 체계 구축 (단기): API 게이트웨이 도입 및 서비스 간 상호 인증(TLS/OAuth2) 의무화 적용.
- 2. 분산 라우팅 적용 (중장기): 분산형 서비스 메시(Service Mesh) 구조 도입으로 SBI 트래픽 분산 처리 체계 구축.

## Ⅵ. 전망
- 향후 SBA는 6G 네트워크에서도 코어 아키텍처의 근간으로 활용될 것이며, AI 기반 네트워크 자동화와 결합하여 진화할 것임.
- 클라우드 네이티브 기반의 유연성을 바탕으로 다양한 산업 융합 서비스 지원의 핵심 인프라로 자리매김할 전망임.
