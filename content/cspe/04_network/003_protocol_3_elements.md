## 미리 알고가기

- 프로토콜: 통신 주체가 데이터를 주고받기 위해 합의한 규칙 집합임
- 구문: 메시지 형식, 필드 길이, 인코딩처럼 비트와 문자의 배치를 정하는 요소임
- 의미: 각 필드와 메시지가 어떤 동작을 요구하는지 해석하는 요소임
- 타이밍: 송수신 순서, 응답 시간, 재전송 조건처럼 시간 관계를 정하는 요소임

## Ⅰ. 개요

- **정의/개념**: 네트워크 프로토콜 3요소는 데이터 교환 규칙을 구문, 의미, 타이밍으로 나눠 통신 가능 여부를 판단하는 기준임
- **배경/필요성**: 송수신자가 같은 메시지를 보내도 형식, 해석, 순서가 다르면 통신이 실패하므로 세 요소를 함께 정의해야 함

## Ⅱ. 특징

- 구문이 맞아야 수신 측이 메시지 경계와 필드 값을 정확히 파싱함
- 의미가 맞아야 같은 필드 값을 보고 동일한 요청과 응답 동작을 수행함
- 타이밍이 맞아야 연결 수립, 재전송, 종료 같은 상태 전이가 어긋나지 않음
- 세 요소 중 하나만 빠져도 상호운용성 시험에서 오류 원인을 특정하기 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 구문 | 의미 | 타이밍 |
|:---|:---|:---|:---|
| 역할 | 메시지 구조와 표현 형식을 정함 | 필드 값과 명령의 해석을 정함 | 송수신 순서와 시간 조건을 정함 |
| 오류 예 | 헤더 길이 불일치, 인코딩 오류가 발생함 | 코드 값 해석이 달라 잘못된 동작이 발생함 | 응답 지연, 중복 전송, 상태 불일치가 발생함 |
| 확인 방법 | 패킷 캡처로 필드 위치와 길이를 확인함 | 규격서와 상태 코드를 대조함 | 시퀀스, 타임아웃, 재전송 로그를 확인함 |

> 요약: 구문은 모양, 의미는 해석, 타이밍은 순서를 정하며 세 요소가 함께 맞아야 통신이 성립함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 메시지 형식 | 헤더, 본문, 체크섬 등 필드 배치를 정의해 파싱 기준을 제공함 |
| 제어 정보 | 요청, 응답, 오류, 확인 같은 동작 의미를 필드 값으로 표현함 |
| 상태 전이 | 연결 수립, 데이터 전송, 종료 과정에서 허용되는 순서를 정함 |
| 시간 조건 | 타임아웃과 재전송 기준을 정해 지연과 유실 상황의 동작을 통제함 |

```text
+--------+      +--------+      +--------+
| Syntax | ---> |Meaning | ---> | Timing |
+--------+      +--------+      +--------+
     message       action         order
```

> 요약: 프로토콜은 메시지 형식, 동작 해석, 상태 순서를 함께 정의하는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 형식작성  | --> | 의미부여  | --> | 순서제어  | --> | 결과확인 |
+----------+     +----------+     +----------+     +----------+
```

1. **형식작성**: 송신 측이 정해진 헤더와 필드 구조에 맞춰 메시지를 만듦
2. **의미부여**: 필드 값으로 요청, 응답, 오류 같은 동작을 표현함
3. **순서제어**: 상태 전이에 맞춰 응답 대기, 재전송, 종료를 수행함
4. **결과확인**: 수신 측 해석과 응답이 규격과 일치하는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 신규 연동 프로토콜을 설계할 때는 필드 형식만 정의하면 구현체별 해석이 갈라지므로 상태 코드 의미와 타임아웃 값을 함께 명세하고 패킷 캡처와 상호운용성 테스트로 확인함
2. 장애 분석에서는 "패킷이 왔다"만으로 성공을 판단하지 말고 구문 오류, 의미 불일치, 타이밍 지연 중 어디서 실패했는지 로그와 재전송 횟수로 분리함

## Ⅶ. 결론

프로토콜 3요소는 통신 규칙을 형식, 해석, 순서로 나눠 상호운용성과 장애 원인을 판단하게 해 주는 기준임.

## 작성 근거(검토용)

- 3요소는 단순 목록이 아니라 통신 실패 원인을 나누는 기준이므로 오류 예와 확인 방법을 함께 배치함
- 표준화 당위 표현 대신 파싱, 해석, 상태 전이의 실제 역할을 문장마다 명시함
- 결론은 상호운용성과 장애 원인 분리라는 출제 의도를 회수함
