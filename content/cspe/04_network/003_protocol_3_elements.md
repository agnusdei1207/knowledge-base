## Ⅰ. 개요
- **정의**: 통신 주체 간 데이터 교환 규칙의 구문·의미·타이밍 3가지 구성 요소임
- **배경/필요성**: 이기종 시스템 간 상호운용성 확보를 위해 통신 규약의 표준화된 구조가 필요함
- **비유**: 외국어 회화에서 문법(구문), 단어 뜻(의미), 말하는 순서(타이밍)에 해당함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로토콜 기본 구조 이해 | 구문·의미·타이밍 각각의 역할 구분 | 3요소를 단순 나열이 아닌 상호 관계로 설명 필요 |

> 요약: 프로토콜은 구문·의미·타이밍 3요소로 구성되어 이기종 간 통신을 표준화함

## Ⅱ. 구성요소
```text
[송신자] --구문(형식)--> [데이터] --의미(해석)--> [수신자]
                            |
                        타이밍(순서/속도)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 구문(Syntax) | 데이터 형식·인코딩·신호 레벨 정의 | 편지의 서식(봉투 양식) |
| 의미(Semantics) | 각 비트 패턴의 의미·제어 정보 해석 규칙 | 편지 내용의 언어 해석 |
| 타이밍(Timing) | 전송 속도·순서·응답 대기 시간 규정 | 대화에서 말하고 듣는 차례 |

> 요약: 구문은 형식, 의미는 해석, 타이밍은 순서를 담당하여 통신 규약을 완성함

## Ⅲ. 절차
```text
구문 정의 --> 의미 매핑 --> 타이밍 설정 --> 프로토콜 합의
```
- 1단계: 구문 정의 — 데이터 단위·필드 크기·인코딩 방식을 명세함
- 2단계: 의미 매핑 — 각 필드 값이 어떤 동작을 뜻하는지 정의함
- 3단계: 타이밍 설정 — 전송 속도·재전송 타이머·순서 제어 규칙을 수립함
- 4단계: 프로토콜 합의 — 송수신 양측이 동일한 규칙을 적용하여 통신을 개시함

> 요약: 형식 → 해석 → 시간 규칙 → 합의 순서로 프로토콜이 확립됨

## Ⅳ. 문제점
- 구문 불일치: 인코딩 차이 — 바이트 순서(Big/Little Endian) 차이로 데이터 파싱 오류 발생
- 의미 모호성: 명세 불완전 — 동일 필드를 다르게 해석하여 호환성 장애 유발
- 타이밍 위반: 타임아웃 불일치 — 재전송 타이머 차이로 세션 단절 발생

> 요약: 3요소 중 하나라도 불일치하면 통신 장애가 발생함

## Ⅴ. 개선방안
1. 단기: ASN.1 등 공식 기술 언어로 구문을 엄밀하게 명세함
2. 중기: RFC 표준 기반 의미 정의와 적합성 시험(Conformance Test) 수행
3. 장기: 프로토콜 자동 생성·검증 도구를 활용한 타이밍 시뮬레이션 체계 구축

> 요약: 형식 명세 강화 → 표준 적합성 시험 → 자동 검증 순으로 개선함

## Ⅵ. 전망
- 발전 방향: IoT·5G 환경에서 경량 프로토콜(CoAP, QUIC) 설계 시 3요소 재정립 필요
- 기술사적 판단: 프로토콜 설계 시 3요소 관점의 체계적 분석이 상호운용성의 핵심임
- 기술사 제언: 신규 프로토콜 도입 시 구문·의미·타이밍 각각의 검증 절차를 표준화할 것을 제안함
