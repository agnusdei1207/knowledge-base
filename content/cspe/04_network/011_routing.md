## Ⅰ. 개요
- **정의**: 라우터가 최적 경로를 설정하는 방식으로, 관리자 수동 입력(정적)과 프로토콜 자동 계산(동적)이 있음.
- **배경 및 필요성**: 네트워크 토폴로지 변화 시 신속한 경로 재설정 및 관리 오버헤드 간의 트레이드오프.
- **출제 의도**: 망 규모와 안정성에 부합하는 정적/동적 라우팅 아키텍처 설계 판단력 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **정적 라우팅** | 관리자가 수동으로 목적지 및 다음 홉 경로를 고정적으로 설정함 | 변하지 않는 종이 지도 |
| **동적 라우팅** | 라우터 간 프로토콜 정보 교환을 통해 최적 경로를 자동 산출함 | 실시간 길안내 내비게이션 |
| **라우팅 테이블** | 라우터가 목적지를 찾기 위해 참조하는 경로 매핑 데이터베이스 | 방향 표시판의 집합 |

> 요약: 정적 라우팅은 작고 보안이 중요할 때, 동적 라우팅은 유연한 대규모 망 구성에 사용됨.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **설정**: 관리자가 직접 경로를 기입하거나 동적 라우팅 프로세스를 활성화함.
2. **교환 (동적)**: 동적 라우팅의 경우 인접 라우터와 네트워크 업데이트 정보를 공유함.
3. **계산 (동적)**: 수집된 토폴로지 기반으로 특정 메트릭(비용)을 계산해 최적 경로를 도출함.
4. **갱신**: 도출된 최종 경로를 라우팅 테이블에 반영하고 패킷 포워딩에 참조함.

> 요약: 정적 방식은 직접 테이블을 채우고, 동적 방식은 상호 정보 교환과 연산을 통해 테이블을 갱신함.

## Ⅳ. 문제점
- 정적 라우팅의 장애 복구 한계 (원인: 관리자가 직접 수정하기 전까지 끊어진 경로로 계속 패킷 전송 발생)
- 동적 라우팅의 리소스 부하 (원인: 정기적 정보 교환 및 경로 알고리즘 연산으로 라우터 CPU 점유율 상승)
- 경로 위조 보안 취약성 (원인: 동적 프로토콜 통신 시 인증 없이 거짓 라우팅 정보를 뿌릴 경우 트래픽 탈취 발생)

## Ⅴ. 개선방안
- **단기 방안**: [단기] 정적 라우팅 트래킹 결합 (SLA 모니터링을 결합해 정적 링크 장애 시 우회 경로를 자동 활성화)
- **중기 방안**: [중기] 동적 라우팅 암호화 인증 적용 (OSPF, BGP 메시지 교환 시 MD5 등 해시 기반 인증 설정)
- **장기 방안**: [장기] SDN 기반 트래픽 엔지니어링 (중앙 컨트롤러가 전체 망 상태를 조망하며 라우팅 테이블 전역 제어)

## Ⅵ. 전망
- 분산형 자율 라우팅에서 소프트웨어 정의(SD-WAN) 기반 중앙 집중 제어 방식으로 진화 중임.
