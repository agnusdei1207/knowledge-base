# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 네트워크 계층(L3)에서 장치의 논리적 위치를 나타내는 주소 체계로, 32비트의 **IPv4**와 128비트의 **IPv6**가 있습니다.
- **필요성**: 우편물을 보낼 때 집 주소가 필요하듯, 수많은 네트워크 사이에서 특정 목적지를 정확히 찾아가기(Routing) 위해 필수적인 '디지털 번지수'입니다.
- **핵심 직관**: **"어디 사는지(Network ID)와 그곳의 누구인지(Host ID)"**를 구분하는 계층적 구조입니다.

## 깊이 이해
- **배경 (주소의 대폭발)**: 1980년대 설계된 IPv4는 약 43억 개의 주소를 가질 수 있었습니다. 당시엔 충분해 보였지만, 1인 1단말을 넘어 IoT 기기까지 폭증하면서 2011년 주소가 바닥났습니다. 이를 해결하기 위해 나온 것이 "무한에 가까운" 주소를 가진 IPv6입니다.
- **작동 원리 (나누고 묶기)**:
  - **IPv4 (32bit)**: `192.168.0.1` 처럼 8비트씩 4칸(옥텟)으로 나눕니다. 서브넷 마스크를 이용해 어디까지가 '동네(네트워크)'인지 정합니다.
  - **IPv6 (128bit)**: `2001:0db8::1` 처럼 16비트씩 8묶음으로 나눕니다. 주소 길이가 4배 늘어난 것뿐만 아니라, 헤더 구조를 단순하게 만들어 처리 속도도 높였습니다.
  - **주소 할당**: 공인 IP(인터넷 전용)와 사설 IP(내부망 전용)를 구분하여 주소를 절약합니다.
- **비유 (전화번호 체계)**:
  - **지역번호(02)**: 네트워크 부분 (어느 도시인가?)
  - **개별번호(1234-5678)**: 호스트 부분 (그 도시의 누구인가?)

## 연결 개념
- **서브네팅(006)**: 하나의 네트워크를 여러 개로 쪼개 효율적으로 쓰는 기술.
- **NAT(011)**: 부족한 공인 IP 하나에 여러 사설 IP를 숨겨서 쓰는 절약 기술.
- **ARP(008)**: IP 주소를 실제 장비의 지문인 MAC 주소로 바꿔주는 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 네트워크상 호스트의 논리적 식별을 위해 계층적(Network/Host) 구조를 가진 L3 주소 체계임.
> 2. **가치**: IPv4의 고갈 문제를 해결하고, IPv6의 풍부한 주소 공간과 단순화된 헤더를 통해 차세대 인터넷 인프라의 확장성을 보장함.
> 3. **판단 포인트**: 전환기에는 IPv4/IPv6 공존 기술(Dual Stack, Tunneling)을 적용하며, 장기적으로는 보안성과 자동설정(SLAAC)이 강화된 IPv6로 이행해야 함.

## Ⅰ. IP 주소 체계의 개요 및 계층적 구조
- **정의**: 호스트 간 데이터 전송을 위해 네트워크 계층에서 사용하는 논리적 주소 지정 방식.
- **계층적 구분**:
  - **Network ID**: 호스트가 속한 특정 네트워크 영역 식별.
  - **Host ID**: 해당 네트워크 내의 개별 호스트 식별.
- **경계 식별**: 서브넷 마스크(IPv4) 또는 프리픽스 길이(IPv6)를 통해 두 영역을 구분.

## Ⅱ. IPv4 vs IPv6 상세 기술 비교

| 비교 항목 | IPv4 (Internet Protocol v4) | IPv6 (Internet Protocol v6) |
|:---:|:---|:---|
| **주소 길이** | 32비트 (2³² ≒ 43억 개) | 128비트 (2¹²⁸ ≒ 무한대) |
| **표기 방식** | 8비트씩 4단위 10진수 (점 표기) | 16비트씩 8단위 16진수 (콜론 표기) |
| **헤더 구조** | 가변 길이 (20~60B), 체크섬 포함 | 고정 길이 (40B), 체크섬 제외 (속도 향상) |
| **주소 할당** | DHCP, 수동 할당 | SLAAC(자동 설정), DHCPv6 |
| **보안 (IPsec)** | 선택 사항 (별도 구현) | 기본 탑재 권고 (설계 시 고려) |
| **전송 방식** | Unicast, Multicast, **Broadcast** | Unicast, Multicast, **Anycast** |

## Ⅲ. IP 주소 고갈 문제와 대응 기술

### 1. 단기/중기적 해결책 (IPv4 수명 연장)
- **NAT/PAT (Network Address Translation)**: 사설 IP 대역을 사용하여 공인 IP 소모 최소화.
- **CIDR (Classless Inter-Domain Routing)**: 클래스 구분 없이 비트 단위로 주소를 할당하여 낭비 방지.
- **Subnetting**: 대규모 네트워크를 세분화하여 효율적 주소 배분.

### 2. 근본적 해결책 (IPv6 전환)
- **SLAAC (Stateless Address Auto-configuration)**: 관리자 개입 없이 장치가 스스로 주소를 생성하여 관리 부하 절감.
- **Anycast 도입**: 가장 가까운 노드로 패킷을 전달하여 서비스 응답 속도 최적화.

## Ⅳ. IPv6의 핵심 특징: 헤더 단순화 및 전송 최적화
- **Fixed Header**: 필수 정보만 40바이트로 고정하여 라우터의 처리 부하 경감.
- **Extension Header**: 옵션 정보를 별도 헤더로 분리하여 필요한 경우에만 처리.
- **Flow Labeling**: 특정 트래픽 흐름에 레이블을 부여하여 실시간 서비스(QoS) 지원 강화.

## Ⅴ. IPv4-IPv6 전환 및 공존 전략

### 1. Dual Stack
- 호스트와 라우터가 IPv4와 IPv6 스택을 모두 구동. 가장 확실하나 자원 소모가 큼.
### 2. Tunneling (6to4, ISATAP)
- IPv6 패킷을 IPv4 패킷 안에 캡슐화하여 IPv4 망을 통과시키는 기술.
### 3. Translation (NAT64/DNS64)
- 주소 변환기를 통해 서로 다른 프로토콜 간의 직접 통신을 지원.

## Ⅵ. 기술사적 통찰: 주소는 '연결의 권리'
- **디지털 주권**: IPv4 자원은 미국 등 선진국에 편중되어 있으나, IPv6는 모든 국가와 기업에 충분한 자원을 제공하여 '디지털 기회 균등' 실현.
- **Hyper-connectivity**: 모든 사물이 IP를 갖는 IoT 시대에는 IPv6가 단순한 주소를 넘어 '장치의 고유 ID'이자 '보안의 출발점'이 됨.
- **결론**: IP 주소 체계의 이해는 단순한 숫자 암기가 아니라, 네트워크의 확장성, 효율성, 보안성을 결정짓는 설계의 핵심 원칙을 이해하는 것임.
