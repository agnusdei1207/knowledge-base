## 미리 알고가기

- IP 주소: 네트워크 계층에서 호스트와 인터페이스 위치를 식별하는 논리 주소임
- 프리픽스: 주소 중 네트워크를 식별하는 앞부분이며 라우팅과 서브넷 분할의 기준임
- IPv4: 32비트 주소 체계이며 점으로 구분한 10진수 표기를 주로 사용함
- IPv6: 128비트 주소 체계이며 콜론으로 구분한 16진수 표기를 사용함

## Ⅰ. 개요

- **정의/개념**: IP 주소 체계는 패킷의 출발지와 목적지를 네트워크 계층에서 식별하고 라우팅 경로를 결정하게 하는 논리 주소 구조임
- **배경/필요성**: 인터넷 규모가 커질수록 주소 공간, 경로 집약, 자동 구성, 보안 확장 요구가 커져 IPv4와 IPv6의 차이를 이해해야 함

## Ⅱ. 특징

- IPv4는 32비트 주소라 표현이 짧지만 공인 주소 고갈을 NAT와 CIDR로 완화해 왔음
- IPv6는 128비트 주소로 주소 공간을 넓히고 자동 구성과 확장 헤더 구조를 제공함
- 두 체계 모두 프리픽스 길이가 라우팅 집약과 서브넷 설계의 기준이 됨
- 전환 기간에는 듀얼 스택, 터널링, 변환을 함께 고려해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | IPv4 | IPv6 |
|:---|:---|:---|
| 주소 길이 | 32비트이며 약 43억 개 주소 공간을 가짐 | 128비트이며 매우 큰 주소 공간을 가짐 |
| 표기 | `192.0.2.10` 같은 점 구분 10진수임 | `2001:db8::1` 같은 콜론 구분 16진수임 |
| 주소 자동 설정 | DHCP와 수동 설정을 주로 사용함 | SLAAC와 DHCPv6를 함께 사용함 |
| 주소 해석 | ARP로 IP와 MAC을 매핑함 | NDP가 이웃 탐색과 주소 확인을 수행함 |
| 운영 쟁점 | NAT, 사설 주소, 주소 고갈 관리가 필요함 | 보안 정책과 장비 지원 여부를 함께 확인해야 함 |

> 요약: IPv4는 부족한 주소를 관리하는 체계이고, IPv6는 큰 주소 공간과 자동 구성을 전제로 한 체계임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 네트워크 프리픽스 | 같은 경로로 묶을 수 있는 주소 범위를 나타내며 라우팅 테이블 크기에 영향을 줌 |
| 호스트 식별부 | 같은 네트워크 안에서 개별 인터페이스를 구분하는 값임 |
| 서브넷 마스크 또는 프리픽스 길이 | 주소 중 네트워크 부분과 호스트 부분의 경계를 정함 |
| 주소 유형 | 유니캐스트, 멀티캐스트, 애니캐스트 등 전달 대상 범위를 구분함 |

```text
IPv4:  192.0.2.10/24
       network | host

IPv6:  2001:db8:10::1/64
       network       | interface
```

> 요약: IP 주소는 프리픽스와 호스트 식별부의 경계가 라우팅과 서브넷 설계를 결정함

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 주소할당  | --> | 프리픽스판단 | --> | 다음홉선택 | --> | 패킷전달 |
+----------+     +----------+     +----------+     +----------+
```

1. **주소할당**: 수동, DHCP, SLAAC 등으로 인터페이스 주소와 프리픽스를 정함
2. **프리픽스판단**: 목적지 주소가 같은 네트워크인지 다른 네트워크인지 확인함
3. **다음홉선택**: 라우팅 테이블의 가장 긴 프리픽스 일치 경로를 선택함
4. **패킷전달**: 인접 노드 주소를 확인한 뒤 링크 계층 프레임으로 보냄

## Ⅵ. 실무 적용 및 유의점

1. IPv4 망에서는 사설 주소와 NAT가 많아 실제 종단 추적이 어려우므로 NAT 테이블, DHCP 로그, 방화벽 세션 로그를 함께 보관해 장애와 보안 추적성을 확보함
2. IPv6 전환에서는 주소가 충분하다는 이유로 보안 정책을 생략하면 외부 노출 경로가 생길 수 있으므로 프리픽스 설계, RA 차단, 방화벽 정책 적중 로그로 확인함

## Ⅶ. 결론

IP 주소 체계는 주소 길이뿐 아니라 프리픽스 설계, 경로 집약, 전환 방식까지 함께 판단해야 함.

## 작성 근거(검토용)

- IPv4와 IPv6의 차이는 단순 크기 비교가 아니라 주소 할당, 이웃 탐색, 전환 운영까지 이어지므로 비교축을 그 기준으로 잡음
- 주소 운영 판단은 라우팅 테이블 크기, NAT 로그, 프리픽스 설계처럼 확인 가능한 요소로 바꿈
- 결론은 주소 공간 설명에서 끝나지 않고 설계 판단 기준을 회수함
