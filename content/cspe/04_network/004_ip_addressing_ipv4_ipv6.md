# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: IP 주소 체계는 **네트워크 계층(L3)**에서 호스트의 논리적 위치를 식별하는 **주소 지정(Addressing)** 규칙으로, 32비트 **IPv4**와 128비트 **IPv6** 두 체계로 나뉜다.
- **왜 필요한가**: 전 세계 수많은 네트워크를 건너 목적지를 찾아가려면(라우팅), 호스트마다 "어느 네트워크의 몇 번인지"를 유일하게 가리키는 논리 주소가 필요하기 때문이다.
- **핵심 직관**: IP 주소는 "**네트워크 부분**(어느 동네)"과 "**호스트 부분**(그 동네 몇 번지)"으로 나뉘며, 그 경계를 알려주는 것이 서브넷 마스크·프리픽스다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 표의 용어는 답안용에 그대로 등장하므로, 여기서 비유·예시와 함께 먼저 이해하고 넘어간다. (서브넷 마스크·프리픽스의 계산 심화는 006에서, 전환 기술은 005에서 다룬다.)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| IP 주소 (Logical Address) | 네트워크상 위치를 나타내는 L3 논리 주소. 이사(네트워크 이동) 시 바뀜 | 집 주소(도로명). MAC=지문(불변)과 대비 |
| 옥텟 (Octet) | IPv4 주소를 8비트씩 4칸으로 끊은 한 칸. 0~255 범위 | 전화번호를 하이픈으로 4칸 나눈 각 칸 |
| 점 10진 표기 (Dotted Decimal) | 32비트를 옥텟마다 10진수로 바꿔 점으로 잇는 표기 | 192.168.0.1 = 이진 32자리를 사람이 읽게 변환 |
| 네트워크 부분 (Network ID) | 주소 앞쪽 비트. "어느 네트워크인가"를 지정 | 우편번호(동네 식별) |
| 호스트 부분 (Host ID) | 주소 뒤쪽 비트. "그 네트워크 안 몇 번 장비인가"를 지정 | 동네 안의 번지수 |
| 클래스 (Class A/B/C) | 네트워크/호스트 경계를 8·16·24비트로 고정했던 초기 분류 방식 | 대·중·소 상자로 미리 정해진 규격 |
| 서브넷 마스크 (Subnet Mask) | 어디까지가 네트워크 부분인지 1로 표시한 32비트 값 | 주소에 자를 대고 네트워크 칸에 형광펜 칠 |
| 프리픽스 (Prefix, /24) | 네트워크 부분의 비트 수를 슬래시로 붙인 CIDR 표기 | 형광펜 칠한 칸의 개수를 숫자로 요약 |
| 공인 IP (Public) | 인터넷 전역에서 유일해 라우팅되는 주소 | 실제 도로명 주소(택배 배송 가능) |
| 사설 IP (Private) | 내부망 전용 예약 대역(10/8, 172.16/12, 192.168/16). 인터넷 직접 불가 | 회사 내선 번호(외부에서 직접 못 걸음) |
| NAT | 사설 IP를 공인 IP로 바꿔 인터넷에 내보내는 변환 (011 참조) | 대표 전화 한 대로 여러 내선을 대변 |
| 브로드캐스트 (Broadcast) | 호스트 부분이 전부 1인 주소. 해당 네트워크 전체에 전송 | 동네 방송 스피커 |
| 루프백 (Loopback, 127.0.0.1) | 자기 자신을 가리키는 주소. 통신 스택 자체 테스트용 | 나에게 보내는 메모 |
| IPv6 | 128비트로 확장한 차세대 주소 체계. 콜론 16진 8묶음 표기 | 자리 수를 대폭 늘려 번호 고갈을 해소한 신 번호판 |
| 유니/멀티/애니캐스트 | 1대1 / 1대다(그룹) / 1대최근접 전송 방식. IPv6는 브로드캐스트 대신 애니캐스트 도입 | 개인 통화 / 단체 문자 / 가장 가까운 지점 연결 |
| SLAAC | 라우터 광고(RA)로 IPv6 주소를 스스로 만드는 자동 설정 | DHCP 없이 스스로 번지수 부여 |

## 깊이 이해
- **배경·문제의식**: L2 MAC 주소(007 참조)는 장비에 고정된 평면 주소라 전 세계 규모에서 경로를 찾을 수 없다. "어느 네트워크 소속인가"를 계층적으로 담는 논리 주소가 있어야 라우터가 네트워크 단위로 경로를 요약해 찾아갈 수 있다. IPv4는 이를 32비트로 설계했으나, 총 약 43억 개(2³²)로는 폭증한 단말·IoT를 감당하지 못해 2011년 IANA 최상위 대역이 고갈됐다. 이 고갈 문제가 IPv6(128비트, 약 3.4×10³⁸개)와 NAT·서브네팅 절약 기법을 낳았다.
- **작동 원리(어떻게+왜)**:
  - **네트워크/호스트 분할**: 32비트를 앞(네트워크)·뒤(호스트)로 나눈다. 라우터는 목적지 주소의 네트워크 부분만 보고 경로를 정하므로, 수억 개 호스트를 네트워크 단위로 묶어 라우팅 테이블을 대폭 줄인다. 경계를 알려주는 것이 서브넷 마스크(예: 255.255.255.0 = 앞 24비트가 네트워크)다.
  - **클래스에서 CIDR로**: 초기에는 경계를 8/16/24비트로 고정한 클래스(A/B/C)를 썼으나, B클래스(약 6.5만 호스트)는 크고 C클래스(254개)는 작아 주소 낭비가 심했다. 그래서 경계를 임의 비트로 자르는 CIDR(프리픽스 /n)로 전환했다(계산 심화는 006).
  - **사설 IP + NAT**: 고갈을 늦추려 내부망은 사설 대역을 재사용하고, 인터넷 나갈 때만 NAT로 공인 IP로 바꾼다(011). 그래서 오늘날에도 IPv4가 버틴다.
  - **IPv6의 단순화**: 128비트로 고갈을 근본 해소하고, 헤더를 40바이트 고정으로 단순화(옵션은 확장 헤더로 분리)해 라우터 처리를 빠르게 했다. 브로드캐스트를 없애고 멀티캐스트·애니캐스트로 대체해 불필요한 전체 전송을 줄였다.
- **비유**: IPv4 32비트는 "자릿수가 부족해진 우편번호 체계"라 동네가 모자란 상황, IPv6 128비트는 "자릿수를 왕창 늘려 지구상 모든 모래알에도 번호를 줄 수 있는" 체계다.
- **구체 예시**:
  - IPv4: `192.168.0.10/24` → 네트워크 `192.168.0.0`, 브로드캐스트 `192.168.0.255`, 사용 가능 호스트 `.1~.254`(254개). `192.168.0.10`은 사설 대역이라 인터넷에 나가려면 NAT 필요.
  - IPv6: `2001:0db8:0000:0000:0000:0000:0000:0001` → 연속 0 묶음을 `::`로 한 번 축약하고 앞 0을 생략해 `2001:db8::1`로 표기. 앞 64비트=네트워크 프리픽스, 뒤 64비트=인터페이스 ID(보통 MAC 기반 EUI-64나 랜덤).
- **흔한 오해·주의점**: `::`(연속 0 축약)는 주소당 **한 번만** 쓸 수 있다(두 번 쓰면 0 개수가 모호해짐). IPv6는 IPv4의 "확장판"이 아니라 헤더 구조가 다른 별개 프로토콜이라 둘은 직접 통신 불가 → 전환 기술(듀얼스택·터널링·변환)이 필요하다(005). "IPv6는 NAT가 필요 없다"는 주소가 충분해서지 NAT가 원천 불가능해서가 아니다.

## 연결 개념
- MAC 주소(007) — L2 물리 주소. IP(논리)와 MAC(물리)를 잇는 것이 ARP(008)
- 서브네팅·CIDR(006) — 네트워크/호스트 경계를 나눠 주소를 효율 배분하는 계산
- IPv6 전환 기술(005) — IPv4·IPv6 공존·상호운용을 위한 듀얼스택·터널링·변환

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IP 주소는 네트워크 부분과 호스트 부분으로 나뉜 L3 논리 주소로, 32비트 IPv4와 128비트 IPv6로 구성됨.
> 2. **가치**: 계층적 주소 구조로 라우팅 테이블을 요약하고, IPv6·NAT·사설 IP로 IPv4 주소 고갈에 대응함.
> 3. **판단 포인트**: 신규 설계는 주소 확장성·헤더 단순화·자동설정(SLAAC) 이점의 IPv6를 기본으로 하되, 레거시 공존은 전환 기술로 처리함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IPv4·IPv6 구조 정확 이해 | 32/128비트, 네트워크/호스트 분할, 헤더 차이 | 옥텟 범위(0~255)·비트 수 오기재 |
| 주소 고갈 원인·대응 | 43억 한계, NAT·사설 IP·CIDR·IPv6 대응 | "IPv6가 무조건 우수" 식 무비교 단정 |
| 주소 유형·자동설정 | 공인/사설, 유니·멀티·애니캐스트, SLAAC | IPv6에 브로드캐스트가 있다는 오류 |

> 요약: 비트 수 암기가 아니라 주소 고갈이라는 문제의식과 IPv4→IPv6 구조 차이를 인과로 서술함.

## Ⅰ. 개요 및 필요성

- 개요: 호스트의 네트워크상 위치를 식별하는 L3 논리 주소 체계(IPv4 32비트·IPv6 128비트)임
- 배경: IPv4 약 43억 주소가 단말·IoT 폭증으로 2011년 IANA 최상위 대역 고갈에 도달한 한계
- 필요성: 계층적 주소로 라우팅을 요약하고, IPv6·NAT·사설 IP로 주소 부족을 해소하기 위함

---

## Ⅱ. 구조 및 구성요소

```text
[IPv4 32비트] 8비트 옥텟 × 4  ->  192 . 168 . 0 . 10 / 24
   / 네트워크 부분(앞 24비트) : 192.168.0
   / 호스트 부분(뒤 8비트)    : .10  (.0=네트워크, .255=브로드캐스트, .1~.254 사용)

[IPv6 128비트] 16비트 × 8묶음 (콜론 16진)  ->  2001:db8::1
   / 네트워크 프리픽스(앞 64비트) : 라우팅 대상
   / 인터페이스 ID(뒤 64비트)     : EUI-64 또는 랜덤
```

| 구성요소 | 개념 | 주요 역할 | 예시 |
|:---|:---|:---|:---|
| 네트워크 부분 | 주소 앞쪽 비트 | 라우팅 단위 식별, 경로 요약 | 192.168.0 / 2001:db8:: |
| 호스트 부분 | 주소 뒤쪽 비트 | 네트워크 내 개별 장비 지정 | .10 / 인터페이스 ID |
| 서브넷 마스크·프리픽스 | 네트워크/호스트 경계 표시 | 경계 판정, 서브넷 분할 근거 | 255.255.255.0 = /24 |
| 주소 유형 | 공인/사설, 유니·멀티·애니캐스트 | 도달 범위·전송 방식 결정 | 10.0.0.0/8, ff00::/8 |

> 요약: IP 주소는 네트워크/호스트 두 부분으로 나뉘고, 그 경계를 마스크·프리픽스가 규정해 라우팅 단위를 이룸.

## Ⅲ. 동작원리 및 흐름도

```text
목적지 IP 확인 → 마스크로 네트워크 부분 추출 → 자기망/외부망 판별 → 라우팅 or ARP → 프레임 전달
```

1. **주소 해석**: 송신 호스트가 목적지 IP와 자신의 서브넷 마스크를 AND 연산해 네트워크 ID를 산출함
2. **경로 판별**: 목적지 네트워크 ID가 자기망과 같으면 직접 전달, 다르면 기본 게이트웨이로 위임함
3. **주소 해소**: L3 IP를 L2 MAC으로 매핑하려 ARP(IPv4)·NDP(IPv6)로 인접 노드 물리주소를 획득함
4. **전달·라우팅**: 라우터가 네트워크 부분만 보고 최장 프리픽스 일치로 다음 홉을 정해 목적지까지 중계함

> 요약: 마스크 AND 연산으로 자기망/외부망을 가르고, IP↔MAC 매핑 후 네트워크 단위로 라우팅함.

## Ⅳ. 특징

- 계층적 주소: 네트워크/호스트 분할로 라우팅 테이블을 네트워크 단위로 요약해 확장성을 확보함
- 주소 고갈 대응: IPv4는 NAT·사설 IP·CIDR로 절약, IPv6는 128비트로 근본 해소함
- IPv6 헤더 단순화: 40바이트 고정 헤더·확장 헤더 분리로 라우터 처리 부하를 낮춤
- 자동 설정: IPv6는 SLAAC(RA 기반)로 DHCP 없이 주소 자동 구성이 가능함
- 전송 방식 재편: IPv6는 브로드캐스트를 폐지하고 멀티캐스트·애니캐스트로 불필요 전송을 축소함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | IPv4 | IPv6 |
|:---|:---|:---|
| 주소 길이 | 32비트(약 43억) | 128비트(약 3.4×10³⁸) |
| 표기 | 점 10진(192.168.0.1) | 콜론 16진(2001:db8::1) |
| 헤더 | 가변(20~60B), 체크섬 有 | 고정 40B, 체크섬 無·확장헤더 |
| 자동설정 | DHCP 필요 | SLAAC·DHCPv6 |
| 전송·보안 | 브로드캐스트 有, IPSec 선택 | 애니캐스트 有, IPSec 통합 권고 |

> 요약: IPv6는 주소 확장·헤더 단순화·자동설정으로 우위이나, 상호 비호환이라 전환 기간 공존 설계가 관건임.

- 고갈·비용 리스크: 공인 IPv4 부족·임대 비용 → 사설 IP+NAT, 장기적으로 IPv6 병행 도입
- 전환 호환 리스크: IPv4·IPv6 직접 통신 불가 → 듀얼스택·터널링·NAT64로 공존(005)
- 관리 지표: IPv6 도입률, NAT 세션 테이블 사용률, 주소 활용률(가용 대비 할당)

---

## Ⅵ. 실무 적용 및 결론

- 주소 계획 수립: 사이트별 프리픽스를 설계하고 사설 대역·서브넷을 부서 단위로 배분함(계산은 006)
- IPv6 단계 도입: 신규 서비스는 듀얼스택으로 시작해 외부 구간부터 IPv6를 활성화함
- 주소 거버넌스: IPAM 도구로 할당 현황·중복·유휴 주소를 추적해 활용률을 관리함
- 결론(조건부 판단): 레거시가 많으면 IPv4+NAT를 유지하며 듀얼스택으로 점진 전환하는 것이 현실적임
- 결론(향후 방향): IoT·모바일 확산으로 종단 간 주소가 요구돼 IPv6 우선 설계가 표준이 되어감
