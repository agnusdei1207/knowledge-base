## Ⅰ. 개요
- **정의**: 32비트 인터넷 주소 체계(IPv4)를 효율적으로 활용하기 위해 서브넷으로 분할하는 기법임.
- **배경 및 필요성**: 클래스 기반 IP 할당의 낭비 방지 및 라우팅 테이블 비대화 해결 필요.
- **출제 의도**: IP 주소 구조(네트워크 ID/호스트 ID) 및 서브넷 마스크 활용 자원 할당 역량 평가

## Ⅱ. 구성요소

```text
+-------------------------+
|  Component Architecture |
+-------------------------+
| [ Node A ] <-> [ Node B]|
+-------------------------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| **IP Address** | 네트워크 단말을 고유 식별하는 32비트 논리 주소 | 건축물의 도로명 주소 |
| **Subnet Mask** | IP에서 네트워크 부와 호스트 부를 구분하는 32비트 필터 | 주소의 '동'과 '번지'를 나누는 기준 |
| **CIDR** | 클래스 제한 없이 서브넷 마스크 비트 수(/24)로 할당하는 방식 | 주소 체계의 유연한 행정 개편 |

> 요약: 서브네팅은 하나의 IP 블록을 여러 소규모 네트워크로 쪼개어 자원 효율성을 높임.

## Ⅲ. 절차

```text
+-------+   +-------+   +-------+   +-------+
| Step1 |-->| Step2 |-->| Step3 |-->| Step4 |
+-------+   +-------+   +-------+   +-------+
```

1. **요구사항 분석**: 분할 개수 및 서브넷 당 호스트 단말 수를 산정함.
2. **호스트 비트 차용**: 기본 네트워크 ID 뒤의 호스트 비트 일부를 서브넷 ID로 차용함.
3. **마스크 생성**: 차용 비트만큼 1로 채워 새로운 서브넷 마스크를 산출함.
4. **대역 할당 및 검증**: 각 서브넷의 네트워크 주소와 브로드캐스트 주소를 계산 후 단말에 부여함.

> 요약: 네트워크 크기에 맞춰 호스트 비트를 빌려 마스크를 조정하고 새 대역을 할당함.

## Ⅳ. 문제점
- IPv4 주소 공간 고갈 (원인: 32비트 체계 한계로 폭발적인 인터넷 기기 수용 불가)
- 서브네팅 오류 시 IP 충돌 (원인: 관리자의 수동 계산 실수로 서브넷 대역 중첩/충돌 발생)
- VLSM 복잡성 (원인: 다양한 서브넷 크기를 가변적으로 쪼갤 경우 라우팅 설정이 복잡해짐)

## Ⅴ. 개선방안
- **단기 방안**: [단기] NAT/PAT 기술 적극 활용 (하나의 공인 IP로 다수 사설 단말이 접속하도록 변환)
- **중기 방안**: [중기] IPAM 솔루션 도입 (주소 할당 관리를 자동화하여 휴먼 에러를 방지)
- **장기 방안**: [장기] IPv6 인프라 전면 마이그레이션 (근본적 주소 부족을 128비트 체계로 완전 해소)

## Ⅵ. 전망
- 클라우드 VPC 및 마이크로서비스 환경에서 동적 서브넷 관리는 핵심 인프라 역량으로 요구됨.
