## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| 정의 | 기업 사용자와 클라우드 서비스(SaaS) 사이에 위치하여 가시성 및 보안 통제를 제공함 |
| 배경 | 미인가 섀도우 IT 사용 증가 및 클라우드 내 민감 데이터 유출 방지 필요 |
| 출제 | API 기반 vs 프록시 기반 연동 방식, 데이터 유출 방지(DLP), 섀도우 IT 탐지 |

## Ⅱ. 구성요소
```text
+--------------+        +--------------+        +--------------+
| User Traffic | -----> |  CASB Proxy  | -----> | SaaS App API |
| (Endpoint)   | Steer  | (Inspect)    | Policy | (O365, SFDC) |
+--------------+        +--------------+        +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 프록시 엔진 | 실시간 트래픽을 가로채어 검사하고 제어하는 인라인 방식임 | 검문소 |
| API 커넥터 | SaaS 제공자의 API와 연동하여 사후 데이터 및 권한 분석함 | 장부 검사원 |
| 정책 관리기 | DLP, 접근 제어 등 클라우드 보안 규정 및 식별 규칙 저장함 | 법전 |

> 요약: 프록시와 API 연동을 통해 실시간 접근 통제 및 사후 데이터 분석 수행함.

## Ⅲ. 절차
```text
+-----------+    +-----------+    +-----------+    +-----------+
| 1. Detect | -> | 2. Analyze| -> | 3. Enforce| -> | 4. Report |
+-----------+    +-----------+    +-----------+    +-----------+
```
1. 탐지 (Detect): 네트워크 로그를 분석하여 미인가 클라우드(섀도우 IT) 파악함.
2. 검사 (Analyze): 사용자의 SaaS 접근 트래픽 및 업로드 데이터 민감도 분석함.
3. 통제 (Enforce): DLP 정책 위반 시 파일 암호화, 접근 차단 등 선제 조치함.
4. 보고 (Report): 침해 위협 및 클라우드 사용 현황을 대시보드로 실시간 리포팅함.

> 요약: 섀도우 IT를 탐지하고 트래픽 분석 후 DLP 정책에 따라 강력 통제함.

## Ⅳ. 문제점
- 암호화 사각: 최신 E2E 암호화 트래픽의 경우 프록시 기반 실시간 검사 한계 존재함.
- API 지연: SaaS 제공자의 API 속도 제한 시 대량 데이터 일괄 검사 지연됨.
- 오탐지: 복잡하고 다양한 클라우드 환경에서 정상 업무 활동이 위협으로 오인됨.

## Ⅴ. 개선방안
- 에이전트 결합 (단기): 엔드포인트 단말 에이전트를 연동하여 암호화 전 데이터 검사함.
- 비동기 처리 (중기): API 기반 사후 검사 비중을 유연하게 늘려 실시간 부하 분산함.
- AI 행위 분석 (장기): 사용자 환경에 최적화된 머신러닝 기반 UEBA 기술 적극 도입함.

## Ⅵ. 전망
- CASB는 독립적 솔루션을 넘어 클라우드 워크로드 전반을 보호하는 통합 CNAPP 플랫폼으로 진화할 것임.
