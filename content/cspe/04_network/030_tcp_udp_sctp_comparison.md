## 미리 알고가기

- 바이트 스트림: 데이터 경계 없이 연속된 바이트 흐름으로 전달하는 방식임
- 데이터그램: 메시지 경계를 유지한 채 독립 단위로 전달하는 방식임
- 멀티호밍: 하나의 연결이 여러 IP 경로를 예비 경로로 보유하는 구조임
- 멀티스트리밍: 하나의 연결 안에서 여러 독립 스트림을 나눠 처리하는 구조임

## Ⅰ. 개요

- **정의/개념**: TCP, UDP, SCTP는 모두 전송 계층에서 애플리케이션 간 통신을 담당하지만, 신뢰성 보장 방식과 전송 단위, 연결 관리 방식이 다름. TCP는 신뢰성과 범용성, UDP는 낮은 지연, SCTP는 캐리어급 안정성과 다중 경로 제어에 강점을 둠
- **배경/필요성**: 웹, 실시간 미디어, 통신사 제어망은 요구 조건이 서로 다르므로 하나의 전송 프로토콜로 모든 상황을 만족시키기 어렵고, 서비스 특성에 맞는 선택 기준이 필요함

## Ⅱ. 특징

- TCP는 연결 지향과 순서 보장에 강해 범용 애플리케이션 기본값으로 쓰임
- UDP는 연결 수립과 재전송을 생략해 지연이 낮고 메시지 경계를 그대로 유지함
- SCTP는 신뢰성과 메시지 단위를 함께 제공하면서 멀티호밍과 멀티스트리밍까지 지원함
- 일반 인터넷에서는 TCP와 UDP 지원이 압도적으로 넓고, SCTP는 통신사와 특수 제어망에서 주로 쓰임

## Ⅲ. 종류 및 비교

| 판단 기준 | TCP | UDP | SCTP |
|:---|:---|:---|:---|
| 연결 방식 | 연결을 먼저 수립한 뒤 바이트 스트림을 전달함 | 별도 연결 없이 데이터그램을 바로 보냄 | 연결 지향이지만 메시지 단위를 유지하는 연관 관계를 형성함 |
| 신뢰성 | 순서 보장, 재전송, 흐름 제어, 혼잡 제어를 제공함 | 전달 보장과 재전송을 기본 제공하지 않음 | 순서 보장과 재전송을 제공하면서 필요 시 스트림별 독립 처리가 가능함 |
| 대표 장점 | 범용성과 상호운용성이 높아 대부분의 서비스에 적용 가능함 | 지연이 작고 구현이 단순해 실시간 서비스에 유리함 | 멀티호밍과 멀티스트리밍으로 제어망 안정성에 강함 |
| 대표 활용 | 웹, 파일 전송, 데이터베이스 연결에 적합함 | DNS, 실시간 음성, 게임, 미디어 전송에 적합함 | SIGTRAN, 5G 제어 평면 같은 통신 인프라에 적합함 |

> 요약: 신뢰성이 최우선이면 TCP, 낮은 지연이 최우선이면 UDP, 경로 이중화와 제어망 안정성이 중요하면 SCTP가 유리함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 연결 관리 | TCP와 SCTP는 상태를 유지하며, UDP는 별도 연결 상태를 유지하지 않음 |
| 전송 단위 | TCP는 바이트 스트림, UDP와 SCTP는 메시지 경계를 유지한 채 전달함 |
| 제어 기능 | TCP는 흐름 제어와 혼잡 제어를, UDP는 최소 기능만, SCTP는 신뢰성과 다중 경로 기능을 함께 가짐 |
| 경로 구조 | SCTP만 기본적으로 멀티호밍을 지원해 주 경로 장애 시 대체 경로로 전환할 수 있음 |

```text
+-----------+     +-----------+     +-----------+
| Reliable  | --> | Low Delay  | --> | Multi-path|
| TCP       |     | UDP        |     | SCTP      |
+-----------+     +-----------+     +-----------+
```

> 요약: 세 프로토콜 차이는 결국 어떤 제어 기능을 기본 제공하고, 어떤 책임을 애플리케이션에 넘기느냐의 차이임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 요구확인 | --> | 신뢰성판단 | --> | 지연판단  | --> | 프로토콜선택 |
+----------+     +----------+     +----------+     +----------+
```

1. **요구확인**: 서비스가 파일 전송인지, 실시간 미디어인지, 제어 평면인지 확인함
2. **신뢰성판단**: 순서 보장과 재전송이 기본으로 필요한지 판단함
3. **지연판단**: 즉시 전달이 더 중요한지, 손실 없는 전달이 더 중요한지 판단함
4. **프로토콜선택**: 일반 범용은 TCP, 실시간성은 UDP, 경로 이중화가 필요한 제어망은 SCTP를 우선 검토함

## Ⅵ. 실무 적용 및 유의점

1. 웹과 업무 시스템은 중간 장비 호환성과 운영 편의 때문에 TCP를 기본으로 두되 짧은 요청이 매우 많으면 QUIC 같은 UDP 기반 대안을 함께 검토하고 연결 수립 지연과 오류율로 확인함
2. 통신사 제어망과 5G 코어처럼 경로 이중화와 메시지 단위 보장이 중요한 구간에서는 SCTP가 유리하지만 일반 인터넷 장비 지원이 제한될 수 있으므로 적용 구간을 폐쇄망 중심으로 두고 절체 시간과 세션 유지율로 확인함

## Ⅶ. 결론

TCP·UDP·SCTP 선택의 핵심은 어느 프로토콜이 더 우수한가가 아니라, 신뢰성·지연·경로 안정성 가운데 무엇을 기본 기능으로 가져가야 하는가에 있음.
