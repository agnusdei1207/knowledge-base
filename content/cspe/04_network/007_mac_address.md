## Ⅰ. 개요
- **정의**: 네트워크 인터페이스 카드(NIC)에 부여된 48비트 물리적 고유 식별자임
- **배경/필요성**: 동일 LAN 내 프레임의 목적지를 식별하기 위해 L2 계층의 고유 주소가 필요함
- **비유**: 사람의 주민등록번호처럼 하드웨어에 고유하게 부여된 번호임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| L2 주소 체계 이해 | OUI + NIC 고유번호 구조 | MAC 스푸핑 가능성, EUI-64와의 관계 언급 |

> 요약: MAC 주소는 48비트 물리 주소로 LAN 내 프레임 전달의 기준이 됨

## Ⅱ. 구성요소
```text
48bit MAC Address
+--------+--------+
| OUI    | NIC ID |
| 24bit  | 24bit  |
+--------+--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| OUI(Organizationally Unique ID) | IEEE가 제조사에 할당한 24비트 식별자 | 자동차 제조사 코드 |
| NIC ID | 제조사가 개별 NIC에 부여한 24비트 고유 번호 | 차량 일련번호 |
| U/L 비트 | 전역/로컬 관리 주소 구분 플래그(7번째 비트) | 공인/사설 주소 구분 표시 |

> 요약: OUI(제조사)+NIC ID(개별 번호)로 전 세계 유일한 물리 주소를 구성함

## Ⅲ. 절차
```text
NIC 제조 --> OUI+NIC ID 할당 --> 프레임 송신 --> MAC 테이블 학습
```
- 1단계: NIC 제조 — 제조사가 IEEE에서 OUI를 할당받음
- 2단계: 주소 부여 — OUI + 고유 일련번호를 ROM/펌웨어에 기록함
- 3단계: 프레임 송신 — 출발지 MAC을 프레임 헤더에 포함하여 전송함
- 4단계: MAC 테이블 학습 — 스위치가 출발지 MAC과 포트를 매핑하여 포워딩 테이블을 구축함

> 요약: 제조 시 할당된 MAC을 기반으로 스위치가 포워딩 테이블을 학습함

## Ⅳ. 문제점
- MAC 스푸핑: 소프트웨어 변경 가능 — 공격자가 MAC을 위조하여 인증을 우회함
- 주소 고갈 우려: 48비트 한계 — IoT 장치 폭증 시 EUI-48 체계의 주소 공간 부족 가능
- 추적 프라이버시: 고정 주소 노출 — 무선 환경에서 MAC 기반 사용자 위치 추적 가능

> 요약: 스푸핑 취약, 주소 공간 한계, 프라이버시 침해가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 802.1X 인증(147 참조)과 포트 보안(148 참조)으로 스푸핑 차단
2. 중기: EUI-64(64비트) 확장 체계 도입으로 주소 공간 확대
3. 장기: MAC 주소 랜덤화(iOS/Android 기본 적용)로 프라이버시 보호

> 요약: 인증 강화 → EUI-64 확장 → 주소 랜덤화로 순차 개선함

## Ⅵ. 전망
- 발전 방향: 무선 환경의 MAC 랜덤화가 표준화되어 프라이버시 보호가 강화됨
- 기술사적 판단: L2 보안은 MAC 신뢰에 의존하므로 상위 계층 인증과 연계가 필수임
- 기술사 제언: MAC 기반 접근 제어 시 802.1X 등 다중 인증 체계를 병행할 것을 제안함
