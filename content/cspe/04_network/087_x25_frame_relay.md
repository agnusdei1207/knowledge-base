# 📖 【암기용】 개념 완전 이해

> 목적: X.25와 프레임 릴레이를 처음 봐도 패킷 교환망의 신뢰 제어 위치와 가상회선 개념을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: X.25와 프레임 릴레이는 가상회선 기반 WAN 패킷 교환 기술이다.
- **왜 필요한가**: 전용회선만으로 지점 간 연결을 모두 만들면 회선 수와 비용이 증가한다. 가상회선은 공용망 안에서 논리 연결을 제공한다.
- **핵심 직관**: X.25는 망이 오류를 세밀하게 챙기는 방식이고, 프레임 릴레이는 오류가 적은 디지털 회선에서 단말과 상위 계층에 더 많은 책임을 넘긴 방식이다.

## 깊이 이해
- **배경·문제의식**: X.25는 아날로그·저품질 회선 시대에 LAPB와 패킷 계층(PLP)으로 오류제어·흐름제어를 망 내부에서 수행했다. 이 제어는 지연과 처리 오버헤드를 만든다.
- **작동 원리**: 프레임 릴레이는 오류검출 후 폐기 중심으로 단순화하고 DLCI로 가상회선을 식별한다. FECN/BECN, DE bit로 혼잡을 알리고 CIR로 계약 대역을 관리한다.
- **비유**: X.25는 택배사가 각 구간마다 내용물을 확인하고 재포장하는 방식이고, 프레임 릴레이는 봉인만 확인하고 빠르게 중계하는 방식이다.
- **구체 예시**: 프레임 릴레이 회선은 PVC별 DLCI를 사용하고 CIR 512kbps, burst 1Mbps처럼 계약 대역과 초과 전송 조건을 둔다.
- **흔한 오해·주의점**: 프레임 릴레이는 오류가 없다는 뜻이 아니다. 망 내부 복구를 줄이고 오류 복구를 상위 계층에 맡긴다.

## 연결 개념
- ATM — 고정 길이 셀 기반 WAN 교환 기술
- MPLS VPN — 프레임 릴레이 WAN의 후속 기업망 구조
- QoS/CIR — 계약 대역과 혼잡 제어 기준

## Ⅰ. 개요 및 필요성

- 개요: 가상회선 기반 WAN 패킷 교환
- 배경: 기업 지점망은 다수 지점 간 전용회선을 모두 구성하기보다 공용망에서 논리 회선을 분리해 비용과 운용을 통제해야 했다.
- 필요성: X.25는 신뢰 제어를, 프레임 릴레이는 고속 중계와 계약 대역 관리를 기준으로 WAN 서비스를 제공했다.

---

## Ⅱ. 구조 및 구성요소

```text
Customer DTE -> Access Link -> Carrier Packet Switch
             / X.25: LAPB + PLP + VC
             / Frame Relay: DLCI + PVC/SVC + CIR
-> Virtual Circuit -> Remote DTE
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| DTE/DCE | 고객 장비와 망 접속 장비 | 라우터, CSU/DSU |
| X.25 LAPB/PLP | 링크·패킷 계층 신뢰 제어 | 오류·흐름제어 포함 |
| DLCI | 프레임 릴레이 가상회선 식별 | local significance |
| CIR | 계약 정보율 | 초과 burst는 DE bit 대상 |

> 요약: 두 기술은 가상회선을 제공하지만 X.25는 계층별 신뢰 제어, 프레임 릴레이는 DLCI와 CIR 기반 경량 중계를 사용함.

---

## Ⅲ. 동작원리 및 흐름도

```text
가입자 프레임 입력 -> VC/DLCI 식별 -> 망 내부 스위칭
-> 혼잡/오류 처리
   / X.25: hop-by-hop error control
   / Frame Relay: FECN/BECN/DE marking
-> 원격 지점 전달
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | PVC/SVC 또는 VC 설정 | circuit status |
| 2 | X.25는 LAPB/PLP로 순서·오류 제어 | retransmission count |
| 3 | 프레임 릴레이는 DLCI로 빠른 중계 | DLCI mapping |
| 4 | 혼잡 시 FECN/BECN/DE bit로 표시 | discard, CIR violation |

> 요약: X.25는 망 내부 복구를 수행하고 프레임 릴레이는 혼잡 표시와 폐기 정책으로 상위 계층 제어를 유도함.

---

## Ⅳ. 특징

| 구분 | X.25 | 프레임 릴레이 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 회선 품질 가정 | 오류 많은 회선 | 오류 적은 디지털 회선 | BER 환경 |
| 제어 위치 | hop-by-hop 오류·흐름제어 | 오류검출 후 폐기 중심 | 지연 감소 |
| 식별자 | logical channel | DLCI | local significance |
| 대역 관리 | 계층 제어 중심 | CIR, DE, FECN/BECN | 계약 대역 kbps/Mbps |

> 요약: 프레임 릴레이는 X.25의 제어 오버헤드를 줄이고 DLCI/CIR 기반 WAN 가상회선 서비스를 제공함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | X.25·프레임 릴레이 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 전용회선 full mesh | 공용망 PVC/SVC | 지점 수, 회선 비용 |
| 비용/성능 | 전용 대역 고정 | CIR 기반 공유망 | 평균 사용률, burst 허용 |
| 운영/위험 | 회선별 관리 | DLCI mapping 관리 | 장애 위치, SLA |

> 요약: 지점 수가 많고 평균 트래픽이 낮으면 가상회선 WAN이 유리하나, 현대망은 MPLS VPN 또는 SD-WAN과 비교해야 함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 혼잡 폐기 | CIR 초과 burst | traffic shaping, DE bit 관리 | FECN/BECN, discard count |
| DLCI 불일치 | 로컬 식별자 매핑 오류 | LMI 상태 점검 | DLCI active/inactive |
| 지연 증가 | X.25 hop-by-hop 제어 | Frame Relay/MPLS 전환 | RTT, retransmission |

> 요약: 운영 리스크는 혼잡 폐기, DLCI 매핑, 제어 오버헤드이며 회선 카운터로 판단함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 계약 대역 | CIR 준수, 초과 discard 임계치 이하 | carrier report, router counter |
| 회선 상태 | PVC active 유지 | LMI status |
| 품질 | RTT, packet loss SLA 충족 | ping, IP SLA |

> 요약: 도입 평가는 CIR 준수, PVC 상태, 지연·손실 SLA를 함께 측정해야 함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 레거시 WAN 분석 시 X.25는 LAPB/PLP 오류제어, 프레임 릴레이는 DLCI/CIR/FECN/BECN을 우선 확인함.
2. 프레임 릴레이 회선은 CIR 이하 shaping과 burst 정책을 라우터 QoS에 반영해 DE 폐기를 줄임.
3. 현대화는 MPLS L3VPN 또는 SD-WAN으로 전환하되 기존 PVC별 애플리케이션 의존성을 사전 식별함.

**결론 (2줄):**
- 기술사 판단: 저품질 회선 신뢰 제어는 X.25, 디지털 회선 기반 기업 WAN 공유망은 프레임 릴레이 관점으로 설명함.
- 향후 방향: 기업 WAN은 가상회선 개념을 MPLS VPN, EVPN, SD-WAN 정책 기반 경로 제어로 계승함.
