## 미리 알고가기

- 가상회선은 공용망 안에 논리적인 통신 경로를 미리 정해 두고 그 경로 번호로 데이터를 보내는 방식임
- PVC는 항상 열어 두는 고정 가상회선이고 SVC는 필요할 때마다 설정하고 해제하는 가상회선임
- DLCI는 프레임 릴레이에서 논리 회선을 구분하는 식별자임
- 홉 단위 오류 제어는 중간 교환기가 구간마다 오류를 확인하고 재전송을 처리하는 방식임

## Ⅰ. 개요

- **정의/개념**: X.25와 프레임 릴레이는 하나의 공용 전송망 위에서 가상회선을 만들어 여러 지점을 논리적으로 연결하는 광역 패킷 교환 기술임
- **배경/필요성**: 지점 수가 늘어날수록 전용회선을 모두 직접 잇는 방식은 비용과 회선 수가 급격히 커지므로 공용망 위에서 필요한 논리 경로만 나눠 쓰는 구조가 필요했음

## Ⅱ. 특징

- 둘 다 물리 회선을 공유하면서 논리 회선 번호로 트래픽을 구분함
- X.25는 망 내부에서 오류 제어와 흐름 제어를 세밀하게 수행해 안정성을 높임
- 프레임 릴레이는 디지털 회선 품질을 전제로 망 내부 제어를 줄여 처리 속도와 효율을 높임
- 회선 품질이 좋아질수록 기능이 무거운 X.25보다 단순한 프레임 릴레이가 더 유리해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | X.25 | 프레임 릴레이 |
|:---|:---|:---|
| 망 내부 제어 | 홉 단위 오류 제어와 흐름 제어를 수행함 | 망은 빠르게 전달하고 오류 복구는 주로 단말과 상위 계층이 맡음 |
| 전송 단위 | 패킷 계층 절차가 무겁고 제어 오버헤드가 큼 | 프레임 단위 전달로 구조가 단순함 |
| 적합한 회선 | 잡음이 많고 품질이 불안정한 환경에 맞음 | 디지털 전송 품질이 안정적인 환경에 맞음 |
| 성능 특성 | 안정성은 높지만 지연과 처리량 손해가 큼 | 속도와 효율은 좋지만 회선 품질 의존도가 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단말 장비 | 사용자 데이터나 업무 트래픽을 공용망에 실어 보내는 종단 장비임 |
| 가상회선 식별자 | X.25의 논리 채널 번호나 프레임 릴레이의 DLCI처럼 논리 경로를 구분하는 값임 |
| 교환망 | 여러 회선을 공유하면서 식별자에 따라 다음 구간으로 전달하는 중간망임 |
| 접속 회선 | 사용자 지점과 공용망을 연결하는 실제 물리 구간임 |
| 망 제어 기능 | X.25에서는 오류와 흐름을 중간망이 적극 관리하고 프레임 릴레이에서는 이 기능을 단순화함 |

```text
+--------+    +----------------+    +----------------+    +--------+
| 지점 A | -> | 공용 패킷 교환망 | -> | 가상회선 식별자  | -> | 지점 B |
+--------+    +----------------+    +----------------+    +--------+
                    |                         |
                    v                         v
               X.25는 망 내부 제어        프레임 릴레이는 빠른 전달
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 회선 설정      | -> | 식별자 부여    | -> | 교환망 전달    | -> | 종단 수신      | -> | 오류 복구      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **회선 설정**: PVC를 미리 준비하거나 SVC를 동적으로 설정함
2. **식별자 부여**: 송신 측이 논리 회선 번호나 DLCI를 붙여 데이터를 보냄
3. **교환망 전달**: 중간망이 식별자를 보고 다음 구간으로 전달함
4. **종단 수신**: 상대 지점이 논리 회선별로 데이터를 분리해 받음
5. **오류 복구**: X.25는 망 내부에서도 오류를 다루고, 프레임 릴레이는 주로 종단과 상위 계층이 복구함

## Ⅵ. 실무 적용 및 유의점

1. 지점 간 레거시 금융망이나 산업망을 운영할 때는 아직 두 기술이 남아 있을 수 있지만 회선 품질과 사업자 지원 범위가 다르면 장애 원인을 좁히기 어려우므로 논리 회선 정보와 계약 속도와 지연 추이를 함께 관리해야 함
2. 프레임 릴레이 구간을 IP 기반 전용망으로 전환할 때는 DLCI와 CIR 같은 기존 운용 기준을 새 경로 정책에 맞게 다시 매핑하고 혼잡 시 손실률과 응답 지연이 얼마나 바뀌는지 확인해야 함

## Ⅶ. 결론

X.25와 프레임 릴레이는 같은 가상회선 계열이라도 오류 제어를 어디서 맡기느냐가 다르므로 회선 품질과 운영 책임 분담을 기준으로 구분해야 함
