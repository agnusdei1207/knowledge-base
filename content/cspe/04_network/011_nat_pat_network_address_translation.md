# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: IP 패킷의 헤더에 있는 주소(IP)와 포트(Port) 정보를 변환하여, 내부 사설 IP를 외부 공인 IP로 바꿔주는 기술입니다.
- **필요성**: IPv4 주소 고갈 문제를 해결하기 위한 일등 공신입니다. 부족한 공인 IP 하나에 수많은 사설 IP 단말을 숨겨서 인터넷을 쓰게 해줍니다.
- **핵심 직관**: **"디지털 교환대"**. 내부의 여러 내선 번호(사설 IP)를 하나의 외부 대표 번호(공인 IP)로 변환하여 통화하게 해줍니다.

## 깊이 이해
- **배경 (시한부 IPv4의 생명 연장)**: IPv6로 넘어가기 전까지 버티기 위해 고안되었습니다. 내부망은 무료로 마음껏 쓸 수 있는 사설 IP 대역(10.x, 192.168.x 등)을 쓰고, 인터넷으로 나가는 관문(라우터/방화벽)에서만 진짜 주소로 옷을 갈아입힙니다.
- **작동 원리 (NAT vs PAT)**:
  - **Static NAT**: 사설 IP 1개를 공인 IP 1개에 1:1로 고정 매핑. 주로 서버를 외부에 공개할 때 씁니다.
  - **Dynamic NAT**: 공인 IP 풀(Pool)에서 남는 주소를 그때그때 빌려주는 방식.
  - **PAT (Port Address Translation)**: **실무에서 가장 많이 쓰는 방식**. 공인 IP 1개 뒤에 '포트 번호'를 붙여 수천 대의 단말을 구분합니다. (예: 1.1.1.1:1001은 A단말, 1.1.1.1:1002는 B단말)
- **비유 (아파트 택배)**:
  - **공인 IP**: 아파트 단지 주소 (택배 기사가 찾아오는 곳)
  - **사설 IP**: 동/호수 (단지 안에서만 의미 있는 주소)
  - **PAT**: 택배 상자에 적힌 '받는 사람 이름(포트)'. 이걸 보고 경비실(NAT 장비)이 어느 집으로 보낼지 결정합니다.

## 연결 개념
- **Port Forwarding**: 외부에서 특정 포트로 접속하면 내부의 특정 서버로 연결해주는 설정. (게임 서버나 웹 서버 운영 시 필수)
- **STUN/TURN**: NAT 뒤에 숨은 기기들끼리 직접 통신(P2P)하기 위해 구멍을 뚫는 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 사설 네트워크의 호스트가 공인 네트워크와 통신할 수 있도록 패킷 헤더의 IP/Port 정보를 동적으로 변환하는 기술임.
> 2. **가치**: IPv4 주소 고갈을 억제하고 내부 네트워크 토폴로지를 외부에 은닉함으로써 1차적인 보안 효과(Obscurity)를 제공함.
> 3. **판단 포인트**: 종단 간 연결성(End-to-End) 파괴로 인한 P2P 서비스 제약을 STUN/TURN 등으로 극복해야 하며, 장기적으로는 NAT가 필요 없는 IPv6로 전환해야 함.

## Ⅰ. NAT 및 PAT의 정의 및 필요성
- **정의**: 사설 IP 주소 대역을 사용하는 호스트가 인터넷 통신을 할 수 있도록 공인 IP 주소로 변환해주는 주소 변환 메커니즘.
- **필요성**:
  - **주소 절약**: 한정된 공인 IPv4 주소 자원의 소모를 최소화.
  - **보안 강화**: 내부 사설 주소 체계를 외부에 노출하지 않아 직접적인 공격 차단.
  - **유연성**: ISP 변경 등으로 공인 IP가 바뀌어도 내부 사설 IP 설정은 유지 가능.

## Ⅱ. NAT의 유형별 상세 매핑 방식

| 유형 | 매핑 방식 | 특징 및 용도 |
|:---:|:---|:---|
| **Static NAT** | 1:1 (Fixed) | 특정 사설 IP를 특정 공인 IP로 고정. 외부 공개 서버(Web, Mail)에 사용. |
| **Dynamic NAT** | N:M (Pool) | 공인 IP 풀 내의 주소를 가용한 대로 할당. 주소 풀 고갈 시 접속 불가. |
| **PAT (NAPT)** | **N:1 (Port)** | 공인 IP 1개에 포트 번호(16bit)를 결합하여 다수의 단말 수용. 가장 일반적. |

## Ⅲ. PAT (Port Address Translation)의 동작 프로세스
1. **송신 (Outbound)**: 내부 호스트(사설IP:Port)가 패킷 송신 -> NAT 장비가 출발지를 (공인IP:새Port)로 치환하고 **Translation Table**에 기록.
2. **수신 (Inbound)**: 외부 서버 응답 수신 -> NAT 장비가 목적지 포트 번호를 테이블에서 조회하여 해당 사설 IP:Port로 변환 후 내부 전달.

## Ⅳ. NAT 환경에서의 제약 사항 및 해결 기술

### 1. End-to-End 연결성 파괴 (보안 및 P2P 문제)
- **문제**: 외부에서 내부로의 세션 개시가 불가능하여 VoIP, 화상회의, P2P 서비스 동작 제한.
- **해결 기술**:
  - **Port Forwarding**: 특정 포트를 특정 내부 IP로 상시 연결.
  - **UPnP (Universal Plug and Play)**: 앱이 스스로 NAT 장비에 포트를 요청하여 개방.
  - **STUN/TURN/ICE**: NAT 트래버설(Traversal) 기술을 통해 종단 간 터널 생성.

### 2. NAT 성능 병목
- **문제**: 모든 패킷의 헤더를 재작성하고 체크섬을 재계산해야 하므로 라우터 CPU 및 메모리 부하 발생.
- **해결**: 하드웨어 가속 기반의 가속 패킷 처리 엔진 활용.

## Ⅴ. NAT vs Proxy Server 비교

| 비교 항목 | NAT (Network Level) | Proxy (Application Level) |
|:---:|:---|:---|
| **작동 계층** | 전송/네트워크 계층 (L3/L4) | 응용 계층 (L7) |
| **변환 방식** | 패킷 헤더 정보 단순 치환 | 세션을 완전히 끊고 새로 맺음 |
| **투명성** | 사용자가 변환 여부 모름 (Transparent) | 브라우저 설정 등 사용자 인지 필요 |
| **주 용도** | 주소 절약 및 외부 인터넷 연결 | 캐싱, 필터링, 익명성 보장 |

## Ⅵ. 기술사적 통찰: '보호'인가 '장벽'인가
- **보안의 부산물**: NAT는 보안을 위해 설계된 것은 아니나, 결과적으로 '외부 직입 불가'라는 강력한 방어벽을 형성함. 이는 제로 트러스트 관점에서는 오히려 관측성(Visibility)을 해치는 요소가 될 수 있음.
- **IPv6 시대의 운명**: IPv6가 도입되면 NAT는 이론적으로 사라져야 함. 하지만 관리의 편의성과 보안상의 은닉 효과 때문에 IPv6 환경에서도 'NAT66'을 쓰려는 요구가 지속될 것으로 보임.
- **결론**: NAT는 주소 고갈이라는 결함을 메우기 위한 임시방편에서 시작했으나, 이제는 현대 네트워크의 보안과 관리 체계를 지탱하는 필수적인 **"아키텍처적 장치"**로 자리 잡음.
