# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: NAT는 라우터가 내부 사설 IP(004 참조)를 외부 공인 IP로 바꿔 인터넷과 통신하게 하는 주소 변환 기술이며, PAT는 여기에 포트 번호를 더해 여러 단말이 공인 IP 1개를 공유하게 하는 확장임.
- **왜 필요한가**: IPv4 공인 주소가 약 43억 개로 고갈되어, 내부에는 무료 사설 대역(10/172.16/192.168)을 쓰고 나갈 때만 공인 IP로 변환해 주소를 절약해야 함.
- **핵심 직관**: 회사 대표번호와 같음. 내부 직원(사설 IP)이 외부에 전화하면 발신번호가 대표번호(공인 IP) 하나로 찍히고, 교환대(PAT)가 내선번호(포트)로 누구 통화인지 구분함.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안(Ⅰ~Ⅵ·표)에 나오는 것들을 미리 풀어 둔 것임. 최상위 키워드는 **사설↔공인 주소 변환(NAT/PAT)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 사설 IP | 내부 전용, 인터넷에 라우팅 안 되는 대역(10/172.16/192.168) | 회사 내선번호 |
| 공인 IP | 인터넷에서 유일하게 라우팅되는 주소 | 외부 대표번호 |
| Inside Local | 내부 단말의 실제 사설 IP | 직원 내선 |
| Inside Global | 변환된 대외용 공인 IP | 대표번호 |
| Static NAT | 사설 IP 1개↔공인 IP 1개 고정 매핑 | 임원 직통 전용회선 |
| Dynamic NAT | 공인 IP 풀에서 남는 것을 그때그때 배정 | 대기 중 빈 회선 배정 |
| PAT(NAPT) | 공인 IP 1개+포트로 다수 단말 다중화 | 대표번호+내선 구분 |
| 변환 테이블 | (사설IP:포트)↔(공인IP:포트) 매핑 기록 | 교환대 통화 대장 |
| 포트 번호 | 세션을 구분하는 16비트 식별자(0~65535) | 내선 구분 번호 |
| Port Forwarding | 외부 요청을 특정 내부 서버로 고정 전달 | 외부 전화를 특정 부서로 연결 |
| Hairpin NAT | 내부에서 자기 공인 IP로 접근 시 되돌리는 변환 | 대표번호로 자기 회사에 전화 |
| NAT Traversal | NAT 뒤 단말끼리 직접 연결(STUN/TURN) | 양쪽 교환대 우회 연결 |

## 깊이 이해
- **배경·문제의식**: IPv4 32비트는 약 43억 개뿐이라 1990년대에 고갈이 예견되었고, IPv6 전면 전환 전까지 시간을 벌 임시방편으로 NAT가 등장함(004의 주소 고갈 대응).
- **작동 원리(어떻게+왜)**: 내부 단말이 패킷을 보내면 라우터가 출발지 사설 IP를 공인 IP로 바꾸고 변환 테이블에 매핑을 기록함. 응답이 오면 테이블을 역참조해 원래 사설 IP로 되돌림. PAT는 여기에 출발지 포트까지 함께 바꿔, 공인 IP가 같아도 포트로 세션을 구분해 수백 대를 1개 IP에 다중화함.
- **비유**: 회사 교환대가 모든 외부 발신을 대표번호로 바꿔 걸고, 걸려온 응답은 통화 대장(변환 테이블)을 보고 해당 내선(사설 IP)으로 연결해 주는 것과 같음.
- **구체 예시**: 가정 공유기가 대표적 PAT임. PC(192.168.0.10:5000)와 폰(192.168.0.11:5000)이 동시에 접속해도 공유기가 공인 IP(1.2.3.4:6001, 1.2.3.4:6002)로 포트를 달리 매핑해 한 회선으로 함께 인터넷을 씀.
- **흔한 오해·주의점**: NAT는 방화벽이 아님. 외부가 내부로 먼저 연결을 못 여는 부수 효과로 '보안 같아' 보이나, 명시적 접근 통제가 아니므로 방화벽을 대체하지 못함.

## 연결 개념
- IP 주소 체계 (004 참조) — 사설/공인 대역 구분과 IPv4 고갈이 NAT의 전제임.
- IPv6 전환 (005 참조) — 주소 공간이 사실상 무한해 NAT 없이 종단 간 통신을 지향함.
- 방화벽 (023 참조) — NAT의 은닉 효과와 달리 정책 기반 접근 통제를 담당함.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NAT는 사설 IP와 공인 IP를 변환 테이블 기반으로 상호 매핑하는 주소 변환 기술이며, PAT는 포트를 더해 공인 IP 1개를 다수 단말이 공유하게 함.
> 2. **가치**: IPv4 고갈 환경에서 무료 사설 대역을 활용해 공인 주소 소비를 최소화하고, 내부 토폴로지를 외부에 은닉함.
> 3. **판단**: 종단 간(End-to-End) 연결성을 깨 P2P·VoIP에 NAT Traversal이 필요하고 변환 테이블이 병목·SPOF이므로, IPv6 환경에서는 NAT 최소화를 지향해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주소 변환 동작 원리 | 변환 테이블 기반 사설↔공인 매핑·역참조 | 포트 다중화(PAT) 없이 NAT만 설명 |
| NAT와 PAT 구분 | IP만 변환 vs IP+포트 다중화 차이 | 두 용어를 동일 개념으로 혼용 |
| 한계·실무 대응 | E2E 단절·NAT Traversal(STUN/TURN)·IPv6 | NAT를 방화벽과 동일시해 서술 |

> 요약: NAT는 '변환 테이블'과 'PAT 포트 다중화'로 주소 절약을 증명하고, E2E 단절 한계와 IPv6 전환으로 결론지어야 함.

## Ⅰ. 개요 및 필요성

- 정의: 라우터가 IP 헤더의 주소(NAT)·포트(PAT)를 변환해 사설망과 공인망을 연결하는 기술임.
- 배경: IPv4 32비트 약 43억 개 고갈로 단말마다 공인 IP를 줄 수 없음.
- 필요성: 무료 사설 대역을 내부에 쓰고 출구에서만 공인 IP로 변환해 주소를 절약하고 내부 구조를 은닉함.

---

## Ⅱ. 구조 및 구성요소

구조도(선형):

```text
내부 단말(사설 192.168.0.10:5000) -> NAT 라우터
  NAT 라우터: 변환 테이블에 (192.168.0.10:5000 <-> 1.2.3.4:6001) 기록
  -> 출발지를 공인(1.2.3.4:6001)으로 치환 -> 인터넷 -> 목적지 서버
  응답 -> NAT 라우터가 테이블 역참조 -> 사설(192.168.0.10:5000)로 복원 -> 내부 단말
```

| 구성요소 | 역할 | 특징 |
|:---|:---|:---|
| NAT 라우터/방화벽 | 주소·포트 변환 수행 | 게이트웨이 경계에 위치 |
| 변환 테이블 | 사설↔공인 매핑 기록·조회 | 세션별 엔트리, 타임아웃 회수 |
| 공인 IP 풀 | 변환에 배정할 공인 주소 집합 | Static·Dynamic·PAT로 활용 |
| 포트 번호 | PAT의 세션 구분자(16비트) | 1 공인 IP에 수천 세션 다중화 |

> 요약: 경계 라우터가 변환 테이블로 사설↔공인을 매핑하며, PAT는 포트를 더해 공인 IP를 다중화함.

---

## Ⅲ. 동작원리 및 흐름도

흐름도(선형):

```text
단말 송신(사설IP:포트) -> NAT 라우터가 공인IP:포트로 치환 + 테이블 기록
  -> 인터넷 -> 서버 응답(목적지=공인IP:포트)
  -> NAT 라우터가 테이블 역참조 -> 사설IP:포트 복원 -> 단말 수신
```

- 1단계: 내부 단말이 사설 IP를 출발지로 패킷을 송신함.
- 2단계: NAT 라우터가 출발지를 공인 IP(PAT는 포트까지)로 치환하고 변환 테이블에 매핑을 기록함.
- 3단계: 외부 서버가 공인 IP:포트를 목적지로 응답을 회신함.
- 4단계: NAT 라우터가 변환 테이블을 역참조해 원래 사설 IP:포트로 복원해 단말에 전달함.

> 요약: NAT 라우터가 송신 시 치환·기록, 수신 시 역참조·복원을 수행하며, 세션 종료·타임아웃 시 엔트리를 회수함.

---

## Ⅳ. 특징

- 주소 절약: PAT는 공인 IP 1개로 이론상 포트 수(약 6.4만)만큼 세션을 수용해 가정·중소망 전체를 1개 IP로 운용함.
- 내부 은닉: 외부에서 내부 사설 구조·단말 수가 보이지 않아 스캐닝 표면을 줄이나, 접근 통제가 아니라 방화벽을 대체하지 못함.
- E2E 단절: 외부가 내부로 먼저 세션을 열 수 없어 P2P·VoIP는 Port Forwarding이나 STUN/TURN 같은 NAT Traversal이 필요함.
- 상태 유지 부담: 세션마다 변환 엔트리를 유지해 대규모 트래픽에서 테이블이 병목·SPOF가 되고, 페일오버 시 세션이 끊길 수 있음.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | NAT(Static/Dynamic) | PAT(NAPT) |
|:---|:---|:---|
| 변환 대상 | IP 주소만 변환 | IP+포트 함께 변환 |
| 매핑 비율 | 사설:공인 = 1:1 | 다수 사설:공인 1개(N:1) |
| 주소 절약 | 낮음(공인 IP 수만큼만 동시 접속) | 높음(1 IP에 수천 세션) |
| 외부 서버 공개 | Static NAT로 내부 서버 공개 용이 | Port Forwarding으로 포트별 공개 |
| 대표 사례 | DMZ 서버 공인 노출 | 가정·사무실 공유기 인터넷 공유 |

> 요약: 내부 서버를 외부에 고정 노출하려면 Static NAT를, 다수 단말이 한 회선을 공유하려면 PAT를 적용하는 것이 원칙임.

리스크·대응(불릿):
- 변환 테이블 병목 — 대량 세션으로 엔트리 폭증 — 세션 타임아웃 튜닝·NAT 장비 이중화.
- E2E 단절 — 외부 인바운드 세션 개시 불가 — STUN/TURN·Port Forwarding으로 우회.
- 로그 추적 곤란 — 다수 사용자가 1 공인 IP 공유로 행위자 식별 난해 — 포트 할당 로그(CGN Logging) 보존.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **가정·중소망 PAT**: 공유기에 공인 IP 1개로 PAT를 적용해 PC·모바일·IoT 수십 대를 한 회선에 다중화.
2. **DMZ Static NAT**: 웹 서버 사설 IP를 공인 IP에 1:1 고정 매핑하고 Port Forwarding으로 80/443만 외부 공개.
3. **통신사 CGN(Carrier-Grade NAT)**: 사설 대역(100.64/10)과 대용량 PAT로 가입자 다수를 소수 공인 IP에 수용하되, 포트 할당 로그를 보존해 추적성을 확보.

**결론(2줄):**
- 기술사 판단: IPv4 잔여 환경이면 PAT로 주소를 절약하되, 외부 공개 서버는 Static NAT+방화벽 정책을 병행해야 함.
- 향후 방향: IPv6는 주소가 사실상 무한해 NAT 없는 종단 간 통신을 지향하나, 은닉·정책 통제는 방화벽으로 별도 확보해야 함.
