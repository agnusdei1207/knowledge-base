# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사설 IP 주소와 공인 IP 주소를 상호 변환하는 기술
- **왜 필요한가**: IPv4 주소 고갈 문제를 해결하고, 내부 네트워크를 외부에 숨겨 보안성을 높이기 위함
- **핵심 직관**: 하나의 공인 IP(집 주소)를 여러 사설 IP(각 방)가 포트 번호를 통해 공유한다.

## 깊이 이해
- **배경·문제의식**: 인터넷의 폭발적 성장으로 43억 개의 IPv4 주소가 빠르게 고갈됨. 모든 기기에 공인 IP를 할당할 수 없어, 내부망 전용의 '사설 IP'를 사용하고 인터넷 접속 시에만 공인 IP로 변환하는 우회책이 필요해짐.
- **작동 원리**: 내부 PC가 패킷을 보내면 공유기(NAT 라우터)가 출발지 사설 IP를 자신의 공인 IP로 변환하여 외부에 전송함. PAT는 여기에 출발지 포트 번호까지 변경·기록하여, 돌아오는 패킷을 어느 PC로 보낼지 식별함.
- **비유**: 회사 대표 전화(공인 IP)와 내선 번호(사설 IP+포트). 외부에서는 대표 전화만 알면 되고, 교환원(NAT)이 내선 번호로 연결해줌.
- **구체 예시**: 가정용 공유기가 1개의 공인 IP를 받아, 스마트폰과 PC에 192.168.0.x 대역의 사설 IP를 할당하고 동시에 인터넷을 쓰게 함(PAT 적용).
- **흔한 오해·주의점**: NAT가 보안의 만병통치약은 아님. 단순 주소 변환일 뿐이며, 외부 악의적 접속을 차단하려면 방화벽 규칙이 별도로 필요함. IPsec 등 페이로드에 IP가 포함되는 프로토콜(VPN)과 충돌(NAT Traversal 필요).

## 연결 개념
- IPv6 전환 기술(듀얼스택, 터널링, 변환)
- IPsec NAT-T(NAT Traversal)
- 방화벽(Firewall) 및 포트 포워딩

## Ⅰ. 개요 및 필요성

- 정의: 사설 IP 주소와 공인 IP 주소를 라우터에서 상호 변환하는 기술
- 배경: 인터넷 급성장으로 인한 IPv4 주소(약 43억 개) 고갈 심화
- 필요성: IPv6 전면 도입 전까지 주소 고갈을 지연(N:1 공유)하고 내부망 은닉(보안) 필요

---

## Ⅱ. 구조 및 구성요소

```text
내부망(사설 IP) -> [NAT 변환 엔진] -> [NAT 테이블] -> 외부망(공인 IP)
                     |                |
                     +-> 통제/필터링   +-> 상태 유지
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 사설 IP (Inside Local) | 내부망에서 호스트가 사용하는 고유 IP | RFC 1918 대역 (10.x, 172.16.x, 192.168.x) |
| 공인 IP (Inside Global) | 외부망으로 나갈 때 변환되는 공인 IP | ISP로부터 할당받은 주소 |
| NAT Table | 세션별 IP/Port 변환 매핑 정보 저장 | 타이머 만료 시 엔트리 삭제 (메모리 관리) |
| NAT Engine | 패킷 헤더(IP, TCP/UDP) 주소 및 체크섬 수정 | L3/L4 헤더 조작에 따른 처리 지연 발생 |

> 요약: 사설 IP와 공인 IP 간의 매핑 상태를 NAT Table에 기록하고, 이를 기반으로 NAT Engine이 헤더를 변환함.

---

## Ⅲ. 동작원리 및 흐름도

```text
패킷 송신 -> 사설IP/포트 식별 -> 공인IP/포트 변환 -> 외부 전송 -> 응답 패킷 수신 -> 테이블 참조 -> 사설IP 재변환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사설 IP 출발 패킷 수신 | ACL(Access Control List) 확인 |
| 2 | 주소 및 포트 변환 | NAT Table 빈 슬롯/포트 할당 |
| 3 | 매핑 정보 기록 및 전송 | IP 헤더 및 L4 체크섬 재계산 |
| 4 | 응답 패킷 역변환 | NAT Table 엔트리 매칭 및 전달 |

> 요약: 내부에서 외부로 나갈 때 매핑을 생성하고, 돌아오는 응답은 매핑 테이블을 참조해 역변환함.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| Static NAT | 사설 IP와 공인 IP를 1:1로 고정 매핑 | 외부에서 내부 서버(웹/메일)로의 인바운드 접속 필요 시 |
| Dynamic NAT | 사설 IP를 공인 IP 풀(Pool)에서 1:1 동적 할당 | 내부 PC 수 ≤ 공인 IP 수 |
| PAT (NAPT) | 1개의 공인 IP에 여러 사설 IP를 포트(L4)로 구분 매핑 | 내부 PC 수 > 공인 IP 수 (대부분의 환경) |

> 요약: 공인 IP 자원 수량과 외부 인바운드 접속 필요 여부에 따라 NAT 방식을 선택함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | NAT (Network Address Translation) | PAT (Port Address Translation) | 선택 기준 |
|:---|:---|:---|:---|
| 변환 계층 | L3 (IP 주소만 변환) | L3 + L4 (IP 주소 + 포트 번호 변환) | 동시 접속 규모 |
| 매핑 방식 | 1:1 | N:1 | 공인 IP 보유량 |
| 프로토콜 호환성 | 대부분의 IP 프로토콜 호환 | 포트 번호를 사용하는 TCP/UDP 한정 | ICMP 등 포트 없는 프로토콜 처리 |

> 요약: 공인 IP가 부족한 환경에서는 PAT가 필수적이나, L4 기반 변환의 한계를 인지해야 함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| IPsec VPN 충돌 | IPsec AH/ESP 페이로드 변조 인지 | NAT-T(UDP 4500 캡슐화) 적용 | IPsec 터널 수립 성공률 |
| 엔드투엔드 연결성 상실 | 외부에서 사설 IP로 직접 라우팅 불가 | 포트 포워딩(Static PAT), STUN/TURN 서버 도입 | P2P(VoIP, WebRTC) 연결 성공률 |
| NAT 장비 과부하 | 수많은 세션에 대한 헤더 재계산 및 테이블 유지 | 세션 타임아웃 튜닝, 하드웨어(ASIC) 기반 NAT 장비 도입 | NAT 세션 테이블 사용률, CPU 부하 |

> 요약: NAT는 종단 간 연결성을 훼손하고 IPsec과 충돌하므로 NAT-T 및 릴레이 서버 도입으로 우회해야 함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. [클라우드] AWS NAT Gateway / Azure NAT Gateway를 통한 Private 서브넷의 아웃바운드 인터넷 접속 구성
2. [보안] 내부망과 DMZ 분리 시, 외부에서 DMZ 서버 접근을 위한 Static NAT(포트 포워딩) 구성
3. [통신] IPsec VPN 환경에서 NAT 통과를 위한 NAT-Traversal(UDP 4500) 및 Keepalive 타이머(20초) 설정

**결론 (2줄):**
- 기술사 판단: 한정된 공인 IP 환경에서는 PAT가 효율적이나, P2P/VPN 요구사항 시 통신 단절 리스크를 점검해야 한다.
- 향후 방향: 근본적 해결책인 IPv6 듀얼스택 및 NAT64 전환을 통해 NAT 장비 병목을 해소해야 편집한다.
