## 미리 알고가기

- NAT: IP 패킷의 출발지 또는 목적지 주소를 중간 장비가 다른 주소로 바꾸는 기술임
- PAT: 하나의 공인 IP에 여러 내부 세션을 포트 번호로 구분해 매핑하는 방식임
- 사설 IP: 내부망에서만 쓰도록 예약된 주소 대역이며 인터넷에서 직접 라우팅되지 않음
- NAT Table: 변환 전후 주소와 포트, 세션 상태를 저장하는 테이블임

## Ⅰ. 개요

- **정의/개념**: NAT와 PAT는 사설망 단말이 공인망과 통신하도록 IP 주소와 포트 정보를 변환하고 그 매핑 상태를 관리하는 기술임
- **배경/필요성**: IPv4 공인 주소가 부족하고 내부 주소 체계를 외부망과 분리해야 하므로 경계 장비에서 주소 변환 절차가 필요함

## Ⅱ. 특징

- NAT는 주소를 변환하고 PAT는 주소와 포트를 함께 변환해 다수 내부 세션을 구분함
- 변환 장비는 응답 패킷을 되돌릴 수 있도록 변환 테이블을 유지해야 함
- 외부에서 내부로 새 연결을 시작하려면 포트 포워딩이나 별도 NAT Traversal이 필요함
- 헤더 재작성 때문에 체크섬, 로그 추적, 일부 응용 프로토콜 처리에 영향을 줌

## Ⅲ. 종류 및 비교

| 판단 기준 | Static NAT | Dynamic NAT | PAT |
|:---|:---|:---|:---|
| 매핑 방식 | 사설 주소와 공인 주소를 1:1로 고정함 | 공인 주소 풀에서 가용 주소를 임시 배정함 | 공인 주소와 포트 조합으로 여러 세션을 구분함 |
| 적합 대상 | 외부 공개 서버처럼 고정 접근이 필요한 대상임 | 내부 단말 수보다 공인 주소 풀이 작을 때 씀 | 다수 내부 단말이 소수 공인 주소로 접속할 때 씀 |
| 상태 관리 | 고정 매핑이라 추적이 단순함 | 풀 고갈과 임대 상태를 관리해야 함 | 포트 고갈과 세션 테이블 크기를 관리해야 함 |
| 제약 | 공인 주소 절감 효과가 작음 | 동시 접속 수가 풀 크기에 묶임 | 종단 간 연결성과 P2P 연결에 제약이 생김 |

> 요약: NAT 유형은 주소 고정성, 공인 주소 수, 세션 상태 관리 방식에 따라 선택함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Inside Local | 내부 단말이 실제로 사용하는 사설 주소임 |
| Inside Global | 외부망에 보이는 변환 후 공인 주소임 |
| Translation Table | 내부 주소·포트와 외부 주소·포트의 매핑을 세션 단위로 저장함 |
| Port Forwarding | 외부 특정 포트를 내부 특정 서버로 고정 연결하는 설정임 |

```text
+--------------+      +----------+      +--------------+
| 10.0.0.10:5000| ---> | NAT/PAT  | ---> | 203.0.113.5:62001 |
+--------------+      +----------+      +--------------+
```

> 요약: NAT/PAT는 내부 세션을 외부 주소와 포트로 바꾸고, 응답이 돌아오면 테이블을 보고 원래 내부 단말로 되돌림

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 패킷수신  | --> | 매핑생성  | --> | 헤더변환  | --> | 응답복원 |
+----------+     +----------+     +----------+     +----------+
```

1. **패킷수신**: NAT 장비가 내부에서 외부로 나가는 패킷을 받음
2. **매핑생성**: 사설 주소와 포트를 공인 주소와 포트에 연결해 테이블에 기록함
3. **헤더변환**: 출발지 주소와 포트를 변환하고 체크섬을 다시 계산함
4. **응답복원**: 외부 응답의 목적지 포트를 테이블에서 찾아 내부 주소로 되돌림

## Ⅵ. 실무 적용 및 유의점

1. 대규모 인터넷 접속망에서는 PAT 포트와 세션 테이블이 고갈되면 신규 접속만 실패할 수 있으므로 동시 세션 수, 포트 사용률, 변환 실패 로그를 기준으로 용량을 산정함
2. VoIP나 P2P 서비스는 NAT 뒤의 단말을 직접 찾기 어려우므로 STUN, TURN, ICE 적용 여부를 확인하고 연결 성공률과 릴레이 사용률로 우회 비용을 점검함

## Ⅶ. 결론

NAT와 PAT는 주소 부족을 숨기는 기술이 아니라 변환 테이블로 내부 세션과 외부 통신을 연결하는 경계 처리 절차임.

## 작성 근거(검토용)

- NAT/PAT는 주소·포트 변환과 상태 테이블이 답안 흐름을 결정하므로 구성요소와 절차를 그 기준으로 재작성함
- 외부 은닉은 완전한 방어 수단이 아니므로 연결성 제약과 로그 추적 문제를 함께 둠
- 결론은 임시방편이라는 평가가 아니라 경계 처리 절차로 역할을 회수함
