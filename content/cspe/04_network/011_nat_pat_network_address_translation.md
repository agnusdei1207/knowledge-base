# 📖 【암기용】 개념 완전 이해

> 목적: NAT와 PAT를 처음 봐도 사설망, 공인 IP, 포트 변환의 차이를 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사설 IP를 공인 IP로 변환해 인터넷 통신을 가능하게 하는 주소 변환 기술
- **왜 필요한가**: IPv4 32비트 주소는 약 43억 개로 제한되며, 기업 내부 단말 수가 공인 IP 수보다 많다. NAT/PAT는 RFC 1918 사설 주소와 소수 공인 주소를 매핑해 주소 고갈을 완화한다.
- **핵심 직관**: 회사 대표 전화번호 하나에 내선번호를 붙여 여러 직원이 외부와 통화하는 구조다.

## 깊이 이해
- **배경·문제의식**: IPv4 공인 주소 부족, 내부망 주소 은닉, 인터넷 접속 비용 절감을 위해 NAT가 보편화되었다. 다만 종단 간 IP 연결성이 깨져 VoIP, IPsec ESP, P2P, 서버 공개에는 추가 설계가 필요하다.
- **작동 원리**: NAT 장비는 패킷의 출발지 IP 또는 목적지 IP를 바꾸고 변환 테이블에 세션을 기록한다. PAT는 IP뿐 아니라 TCP/UDP 포트까지 바꿔 `사설 IP:포트` 여러 개를 `공인 IP:포트` 하나의 조합 공간으로 다중화한다.
- **비유**: 아파트 경비실이 외부 택배 송장을 대표 주소로 받고, 내부 동·호수 표로 세대까지 전달하는 방식이다.
- **구체 예시**: `10.0.0.10:51512 -> 203.0.113.5:40001`, `10.0.0.11:51512 -> 203.0.113.5:40002`처럼 포트 번호로 내부 단말을 구분한다.
- **흔한 오해·주의점**: NAT는 방화벽과 동일하지 않다. 주소 변환은 접근통제가 아니므로 상태기반 ACL, 로그, 포트포워딩 범위를 별도로 설계해야 한다.

## 연결 개념
- RFC 1918 사설 주소 — 10/8, 172.16/12, 192.168/16 대역의 내부 주소 기준
- IPv6 전환 — IPv6에서는 주소 부족 완화 목적 NAT 의존도가 낮아짐
- IPsec NAT-T — UDP 4500 캡슐화로 NAT 환경의 VPN 통과 지원

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: NAT/PAT는 주소 절약 기술로만 쓰지 말고, 세션 테이블·포트 고갈·로그 추적·종단 간 연결성 훼손까지 함께 판단한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NAT(Network Address Translation)는 IP 주소를, PAT(Port Address Translation)는 IP와 TCP/UDP 포트를 함께 변환하는 IPv4 주소 공유 기술이다.
> 2. **가치**: RFC 1918 사설 주소를 공인 IP 소수와 매핑해 IPv4 주소 소모를 줄이고 내부 주소 체계를 외부 라우팅 테이블에서 분리한다.
> 3. **판단 포인트**: 포트 65,536개 한계, 세션 타임아웃, ALGs, 로그 보존, IPsec NAT-T 지원 여부를 함께 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NAT와 PAT 차이 확인 | 주소 변환 vs 주소+포트 변환, 정적/동적/PAT 구분 | NAT를 방화벽으로 단정 |
| IPv4 주소 부족 대응 이해 확인 | RFC 1918, 공인 IP 절약, 포트 다중화 | IPv6 환경에서도 같은 목적이라고 서술 |
| 운영 리스크 판단 확인 | 포트 고갈, 세션 테이블, 로그 추적, NAT-T | 포트포워딩과 접근통제 누락 |

> 요약: NAT/PAT 문제는 주소 변환 방식보다 세션 식별성과 운영 리스크를 함께 써야 득점 가능하다.

---

## Ⅰ. 개요 및 필요성

- 정의: 사설 IP와 공인 IP 간 주소·포트를 매핑하는 변환 기술
- 배경: IPv4 32비트 주소 공간의 한계로 내부 단말마다 공인 IP를 배정하기 어려움
- 필요성: 내부 주소 체계를 보존하면서 인터넷 접속, 서버 공개, 망 분리를 구현해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Inside Host -> NAT/PAT Gateway -> Public Internet
  / Translation Table
  / ACL and Port Forwarding
  / Log and Timeout Policy
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Inside Local | 내부 단말의 사설 IP | RFC 1918 대역 사용 |
| Inside Global | 외부에서 보이는 공인 IP | ISP 할당 주소 |
| Translation Table | 내부 IP:포트와 공인 IP:포트 매핑 | TCP/UDP 세션 단위 기록 |
| Port Forwarding | 외부 요청을 내부 서버로 전달 | 정적 NAT 또는 DNAT 사용 |

> 요약: NAT/PAT 구조는 내부 주소, 외부 주소, 변환 테이블, 포트 정책으로 세션을 식별한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Outbound Packet -> Source IP/Port Lookup -> Public IP/Port Rewrite
  -> Internet Response -> Mapping Lookup -> Private IP/Port Restore
  -> Timeout or Session Close -> Table Entry Remove
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 내부 단말이 TCP/UDP 세션 생성 | 5-tuple 식별 |
| 2 | NAT 장비가 공인 IP와 가용 포트 할당 | 포트 범위 1024~65535 |
| 3 | 응답 패킷을 변환 테이블로 역매핑 | 세션 타임아웃 정책 |
| 4 | 종료 또는 유휴 시간 초과 시 항목 제거 | 테이블 사용률 70% 이하 |

> 요약: PAT는 5-tuple과 포트 풀을 기준으로 다수 내부 세션을 하나 이상의 공인 IP에 다중화한다.

---

## Ⅳ. 특징

| 구분 | NAT/PAT | 대안/비교 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 주소 절약 | 공인 IP 1개로 다수 단말 접속 | 공인 IP 직접 배정 | IPv4 32비트, RFC 1918 |
| 연결성 | 외부에서 내부 직접 접근 제한 | IPv6 종단 간 통신 | 포트포워딩 필요 |
| 운영 한계 | 포트·세션 테이블 고갈 가능 | 공인 IP 증설 | TCP/UDP 포트 65,536개 |
| 프로토콜 영향 | IP 헤더 내 주소 포함 프로토콜 처리 필요 | ALG, NAT-T | IPsec NAT-T UDP 4500 |

> 요약: NAT/PAT는 IPv4 주소 절약에는 유리하지만 포트 고갈과 종단 간 연결성 훼손을 설계 조건으로 다뤄야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정적 NAT | 동적 NAT/PAT | 선택 기준 |
|:---|:---|:---|:---|
| 매핑 구조 | 1:1 고정 매핑 | N:1 또는 N:M 동적 매핑 | 서버 공개는 정적, 사용자 인터넷은 PAT |
| 비용/주소 | 공인 IP 수만큼 필요 | 공인 IP 풀 절약 | 동시 세션 수와 포트 풀 계산 |
| 운영/추적 | 로그 단순 | 포트 로그 필수 | 사용자 식별은 IP+포트+시간 필요 |

> 요약: 외부 공개 서버는 정적 NAT, 대규모 내부 사용자 인터넷 접속은 PAT가 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 포트 고갈 | 공인 IP 1개당 포트 수 제한 | 공인 IP 풀 증설, 세션 타임아웃 조정 | allocated ports 70% 이하 |
| 추적 실패 | 로그에 포트·시간 누락 | NAT 로그에 IP, port, timestamp 기록 | 로그 보존 6개월 이상 |
| 애플리케이션 장애 | 페이로드에 IP 포함 | ALG 적용, STUN/TURN, NAT-T | 실패 세션 수, SIP 오류율 |

> 요약: NAT/PAT 운영 리스크는 포트 풀, 로그 완전성, 프로토콜 보정 기능으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 세션 용량 | 최대 동시 세션의 1.5배 | NAT table counter |
| 포트 사용률 | 공인 IP별 70% 이하 | port allocation metric |
| 장애 분석 | 변환 전후 IP:포트 추적 가능 | flow log, syslog, NetFlow |

> 요약: NAT/PAT 성공 여부는 동시 세션, 포트 사용률, 변환 로그 추적성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 사용자 인터넷 구간은 PAT를 기본 적용하고 공인 IP당 동시 포트 사용률 70% 이하로 용량 산정함
2. 외부 공개 서버는 정적 NAT와 ACL을 함께 적용하고 허용 포트는 TCP 443 등 필요한 서비스로 제한함
3. VPN·VoIP는 IPsec NAT-T UDP 4500, SIP ALG, STUN/TURN 지원 여부를 사전 검증함

**결론 (2줄):**
- 기술사 판단: 내부 사용자 접속은 PAT, 외부 공개 서비스는 정적 NAT, 종단 간 연결이 필수인 서비스는 IPv6 또는 프록시 구조를 선택함
- 향후 방향: IPv6 전환 확대와 함께 NAT 의존도를 줄이고, 남는 IPv4 구간은 로그·포트 용량 기준으로 운영해야 함
