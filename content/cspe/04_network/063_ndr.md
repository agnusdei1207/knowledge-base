## Ⅰ. 개요
- **정의**: 네트워크 트래픽을 실시간 분석하여 이상 행위를 탐지·대응하는 보안 솔루션
- **배경/필요성**: 암호화 트래픽 증가로 시그니처 기반 IDS만으로는 내부 위협 탐지가 한계임
- **비유**: 도로 위 차량 흐름 패턴을 분석해 수상한 주행을 감지하는 교통 감시 시스템

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 네트워크 행위 기반 탐지 원리 | 메타데이터·플로우 분석 + ML 이상탐지 | IDS(시그니처)와 NDR(행위 기반) 차이 구분 |

> 요약: 네트워크 메타데이터·플로우를 ML로 분석하여 알려지지 않은 위협을 탐지함

## Ⅱ. 구성요소
```text
[Network TAP/Mirror] ---> [Sensor/Probe]
                               |
                               v
                      [Analytics Engine]
                          |        |
                          v        v
                       [ML Model] [Threat Intel]
                          |        |
                          +---+----+
                              v
                        [Response Module]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Sensor/Probe | TAP·미러 포트에서 패킷·플로우 수집 | 도로 위 과속 감지 카메라 |
| Analytics Engine | 메타데이터 파싱·베이스라인 비교·이상 탐지 | 교통량 통계 분석 센터 |
| ML Model | 정상 트래픽 학습 후 편차 기반 이상 스코어링 | 평소 운전 패턴과 비교 |
| Response Module | 세션 차단·SOAR(062) 연계 자동 대응 | 위반 차량 자동 단속 |

> 요약: 센서-분석엔진-ML-대응 모듈로 네트워크 이상 행위를 탐지·차단함

## Ⅲ. 절차
```text
Step1 --> Step2 --> Step3 --> Step4
트래픽수집  베이스라인  이상탐지   대응/격리
           생성
```
- 1단계: TAP·미러 포트에서 패킷 헤더·플로우 메타데이터를 수집함
- 2단계: 프로토콜·세션·호스트별 정상 트래픽 베이스라인을 생성함
- 3단계: ML 모델이 베이스라인 편차를 스코어링하여 이상 이벤트를 탐지함
- 4단계: 위험도 기반 세션 차단·SOAR 연계·포렌식 데이터 보존을 수행함

> 요약: 수집-베이스라인-이상탐지-대응의 4단계로 네트워크 위협에 대응함

## Ⅳ. 문제점
- 암호화 한계: TLS 1.3 등 종단 암호화 — 페이로드 분석 불가로 탐지율 저하
- 베이스라인 오차: 트래픽 패턴 변동이 큰 환경 — 오탐·미탐 비율 증가
- 동서 트래픽 사각: 센서가 경계에만 배치 — 내부 횡이동 공격 탐지 누락

> 요약: 암호화·베이스라인 오차·내부 트래픽 사각이 탐지 정확도를 저하시킴

## Ⅴ. 개선방안
1. 단기: JA3/JA4 핑거프린팅으로 암호화 트래픽의 메타데이터 기반 탐지 보완
2. 중기: 적응형 베이스라인(시간대·요일별 프로파일)으로 오탐률 감소
3. 장기: 마이크로세그멘테이션(066) 연계로 동서 트래픽 센서 배치 확대

> 요약: 메타 분석·적응형 베이스라인·내부 센서 확대로 탐지 정확도를 개선할 필요

## Ⅵ. 전망
- 발전 방향: XDR 구성요소로 EDR·SIEM과 통합되어 엔드투엔드 가시성 확보
- 기술사적 판단: 클라우드 환경에서는 vTAP·eBPF 기반 센서로 전환 추세임
- 기술사 제언: 제로트러스트(064) 아키텍처와 연계하여 내부 트래픽 모니터링을 강화할 필요
