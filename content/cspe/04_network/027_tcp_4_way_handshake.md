## 미리 알고가기

- FIN: 더 이상 보낼 데이터가 없음을 알리는 TCP 제어 플래그임
- Half-Close: 한쪽 송신만 닫히고 반대 방향 수신은 계속 열려 있는 상태임
- TIME_WAIT: 최종 ACK 뒤 지연 패킷과 재전송 FIN을 처리하기 위해 잠시 기다리는 상태임
- CLOSE_WAIT: 상대 FIN을 받았지만 애플리케이션이 아직 소켓을 닫지 않은 상태임

## Ⅰ. 개요

- **정의/개념**: TCP 4-way handshake는 전이중 연결의 양 방향을 각각 독립적으로 닫기 위해 FIN과 ACK를 네 번 주고받는 연결 해제 절차임. 한쪽이 송신을 마쳤다고 해서 상대도 동시에 끝난 것이 아니므로 종료도 방향별로 따로 확인함
- **배경/필요성**: 서버가 아직 응답 데이터를 보내는 중일 수 있으므로 종료를 한 번에 처리하면 데이터 유실이 생길 수 있어, 송신 종료와 수신 종료를 분리한 절차가 필요함

## Ⅱ. 특징

- 한쪽 송신 종료와 반대 방향 송신 종료를 분리해 ACK 이후에도 반대 방향의 남은 데이터를 전송할 수 있음
- 먼저 종료를 시작한 쪽은 최종 ACK 뒤 TIME_WAIT에 들어가 늦게 도착한 세그먼트 영향을 막음
- CLOSE_WAIT이 오래 남는 경우는 대체로 애플리케이션이 소켓을 제대로 닫지 못한 상황임
- 짧은 세션이 반복되는 구조에서는 TIME_WAIT 소켓이 누적되어 사용 가능한 로컬 포트가 줄어들 수 있음

## Ⅲ. 종류 및 비교

| 상태 | 의미 | 운영상 해석 |
|:---|:---|:---|
| FIN_WAIT | 먼저 종료를 시작한 쪽이 상대 ACK나 FIN을 기다리는 상태임 | 정상 종료 중이지만 세션 수가 많으면 자원 점유가 늘 수 있음 |
| CLOSE_WAIT | 상대 FIN을 받은 뒤 로컬 애플리케이션 종료를 기다리는 상태임 | 오래 남으면 애플리케이션의 `close()` 누락을 의심해야 함 |
| TIME_WAIT | 최종 ACK 뒤 일정 시간 동안 지연 패킷을 흡수하는 상태임 | 정상 상태지만 과도하면 짧은 연결 구조를 점검해야 함 |

> 요약: FIN_WAIT과 TIME_WAIT은 대체로 정상 종료 흐름이고, CLOSE_WAIT 장기 누적은 애플리케이션 문제로 보는 경우가 많음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Active Closer | 먼저 FIN을 보내 종료를 시작하는 쪽이며 최종적으로 TIME_WAIT을 맡는 경우가 많음 |
| Passive Closer | 상대 FIN을 받고 남은 전송을 마친 뒤 자신의 FIN을 보내는 쪽임 |
| FIN과 ACK | 방향별 송신 종료와 수신 확인을 분리해 전달하는 제어 정보임 |
| 종료 상태 테이블 | 커널이 각 소켓 상태를 유지하며 언제 자원을 회수할지 결정하는 기준이 됨 |

```text
+---------+                              +---------+
| Active  |                              | Passive |
+---------+                              +---------+
    | -------- FIN ------------------>       |
    | <------- ACK -------------------       |
    | <------- FIN -------------------       |
    | -------- ACK ------------------>       |
    | ----- TIME_WAIT ---------------        |
```

> 요약: 연결 종료 구조는 먼저 끊겠다는 선언과 상대 종료 확인을 양 방향으로 나눠 처리하는 방식임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| FIN전송  | --> | ACK수신  | --> | FIN수신  | --> | ACK전송  |
+----------+     +----------+     +----------+     +----------+
```

1. **FIN전송**: 먼저 닫는 쪽이 더 이상 보낼 데이터가 없음을 알림
2. **ACK수신**: 상대가 이를 확인하고 필요하면 남은 데이터를 계속 보냄
3. **FIN수신**: 상대도 자신의 송신을 마치면 FIN을 보냄
4. **ACK전송**: 마지막 ACK를 보낸 뒤 먼저 닫은 쪽은 TIME_WAIT을 거쳐 자원을 회수함

## Ⅵ. 실무 적용 및 유의점

1. 프록시나 API 게이트웨이처럼 짧은 세션이 많은 구간에서는 TIME_WAIT이 급증해 포트 고갈이 날 수 있으므로 Keep-Alive와 커넥션 풀을 우선 적용하고 TIME_WAIT 소켓 수와 로컬 포트 사용률로 확인함
2. 애플리케이션 서버에서 CLOSE_WAIT가 계속 남으면 네트워크보다 코드의 소켓 종료 누락을 먼저 의심해야 하므로 예외 처리 경로의 `close()`를 점검하고 CLOSE_WAIT 수와 파일 디스크립터 사용량으로 확인함

## Ⅶ. 결론

TCP 4-way handshake는 양방향 송신 종료를 각각 확인하고 TIME_WAIT 동안 지연 세그먼트를 처리한 뒤 연결 자원을 회수하는 절차임.
