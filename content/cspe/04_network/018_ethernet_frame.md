## 미리 알고가기

- MAC 주소: 같은 LAN에서 송수신 장비를 구분하는 48비트 주소임
- EtherType: 상위 프로토콜이 IPv4, ARP, IPv6 가운데 무엇인지 알려 주는 값임
- FCS: 프레임이 전송 중 손상됐는지 확인하는 오류 검사용 값임
- MTU: 한 번에 실을 수 있는 최대 상위 데이터 크기임

## Ⅰ. 개요

- **정의/개념**: 이더넷 프레임은 LAN에서 데이터를 주고받을 때 송수신 MAC 주소, 상위 프로토콜 정보, 페이로드, 오류 검사용 값을 담는 2계층 전송 단위임
- **배경/필요성**: 물리 신호만으로는 프레임 시작점, 수신 대상, 데이터 손상 여부를 알 수 없으므로 공통된 프레임 형식이 필요함

## Ⅱ. 특징

- 프레임은 시작 표시, 주소, 프로토콜 구분, 데이터, 오류 검출 값을 정해진 순서로 담음
- 최소 크기와 최대 크기가 정해져 있어 장비 간 처리 기준을 맞출 수 있음
- FCS는 오류를 검출하지만 손상된 프레임을 복구하지는 않고 폐기함
- VLAN 태그나 점보 프레임을 쓰면 길이와 MTU 계산을 경로 전체에서 맞춰야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Ethernet II | IEEE 802.3 |
|:---|:---|:---|
| 구분 필드 | 2바이트 필드에 상위 프로토콜 종류를 직접 기록함 | 같은 위치 필드에 데이터 길이를 기록하고 상위 식별은 LLC로 보완함 |
| 실무 활용 | TCP/IP 기반 일반 네트워크에서 주로 사용됨 | 표준 구조 설명과 일부 제어 환경에서 의미가 있음 |
| 프로토콜 식별 | EtherType 값으로 IPv4, ARP, IPv6를 바로 식별함 | LLC와 SNAP 해석이 추가로 필요함 |
| 확인 포인트 | 패킷 분석에서 EtherType 값을 먼저 확인함 | 길이 필드와 LLC 헤더를 함께 확인함 |

> 요약: 실무 캡처에서는 Ethernet II를 주로 보지만, IEEE 802.3은 길이와 LLC 해석을 설명할 때 필요함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Preamble과 SFD | 수신 측이 비트 동기를 맞추고 프레임 시작 지점을 인식하도록 돕는 구간임 |
| Destination과 Source MAC | 프레임을 어디로 보내고 누가 보냈는지 나타내며 스위치 포워딩의 기준이 됨 |
| EtherType 또는 Length | 상위 프로토콜 식별 또는 데이터 길이 해석에 쓰이며 디캡슐레이션 방향을 정함 |
| Payload와 FCS | 실제 전송 데이터와 오류 검사용 값을 담으며 FCS가 맞지 않으면 프레임을 폐기함 |

```text
+----------+-----+---------+---------+-----------+---------+------+
|Preamble  |SFD  |Dst MAC  |Src MAC  |Type/Len   |Payload  | FCS  |
+----------+-----+---------+---------+-----------+---------+------+
```

> 요약: 이더넷 프레임은 시작 표시, 주소, 프로토콜 구분, 데이터, 오류 검출 값을 차례로 담는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+
| 캡슐화   | --> | 주소판단  | --> | 데이터전송 | --> | FCS검사 |
+----------+     +----------+     +----------+     +----------+
```

1. **캡슐화**: 상위 계층 데이터 앞뒤에 MAC 주소와 FCS를 붙여 프레임을 만듦
2. **주소판단**: 송신 장비가 목적지 MAC을 기록하고 스위치는 이 값을 보고 출력 포트를 정함
3. **데이터전송**: 프레임이 물리 매체를 따라 전달되며 필요하면 VLAN 태그가 함께 실림
4. **FCS검사**: 수신 장비가 같은 방식으로 FCS를 계산해 값이 다르면 프레임을 버림

## Ⅵ. 실무 적용 및 유의점

1. 데이터센터나 스토리지망에서 점보 프레임을 쓸 때는 중간 장비 MTU가 다르면 단절이나 재전송이 생기므로 전 구간 MTU를 일치시키고 프레임 드롭 수와 처리량으로 확인함
2. VLAN 환경에서는 802.1Q 태그가 프레임 길이에 영향을 주므로 액세스와 트렁크의 태그 처리 방식을 맞추고 태그 불일치 건수와 CRC 오류율로 확인함

## Ⅶ. 결론

이더넷 프레임은 LAN 전달의 기본 단위이므로 필드 구조와 길이 제약을 알아야 VLAN, 스위칭, 장애 분석을 정확히 설명함.

## 작성 근거(검토용)

- 이더넷 프레임은 성능보다 필드 해석과 오류 검출이 답안 흐름을 결정하므로 EtherType, Length, FCS, MTU를 중심으로 구성함
- 막연한 필요 표현은 패킷 분석 확인 포인트와 MTU·CRC 검증으로 바꿈
- 결론은 필드 구조가 실제 장애 분석에 연결된다는 판단을 회수함
