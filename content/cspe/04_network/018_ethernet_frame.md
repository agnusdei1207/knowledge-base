# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 이더넷 프레임은 L2(데이터링크) 계층에서 데이터를 실어 나르는 전송 단위로, 앞뒤에 프리앰블·MAC 주소·타입·FCS 같은 규격 필드를 붙인 봉투임(IEEE 802.3 표준이 필드 배치와 길이를 정의함).
- **왜 필요한가**: 같은 LAN의 여러 장치가 하나의 매체를 공유하므로, 수신 대상(목적지 MAC)·발신자·데이터 종류·오류 여부를 프레임 규격으로 명확히 표시해야 충돌·오배송 없이 주고받을 수 있음.
- **핵심 직관**: 택배 상자와 같음. 겉면에 받는 사람(목적지 MAC)·보내는 사람(출발지 MAC)·내용물 종류(Type)·개봉 전 파손 검사 봉인(FCS)을 붙여야 물류(스위치)가 올바르게 분류·전달함.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 표기는 답안 Ⅰ~Ⅵ에 그대로 등장하므로 먼저 이해해 둠. 상위 핵심 키워드는 **프레임(L2 전송 단위, 헤더+데이터+트레일러)**임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 프리앰블(Preamble, 7B) | 송수신 클럭 동기용 반복 비트열(10101010…) | 방송 전 "삐~" 신호음 |
| SFD(1B) | 프레임 시작 구분자, 프리앰블 끝을 알림(10101011) | "지금부터 본방 시작" |
| 목적지 MAC(6B) | 받는 장치의 물리 주소 | 받는 사람 주소 |
| 출발지 MAC(6B) | 보내는 장치의 물리 주소 | 보내는 사람 주소 |
| Type/Length(2B) | 상위 프로토콜 종류(≥0x0600) 또는 길이(≤1500) | 내용물 분류표(IPv4=0x0800) |
| Payload(46~1500B) | 실제 데이터(상위 계층 패킷) | 상자 내용물 |
| 패딩(Padding) | 46B 미만 시 채워 넣는 더미 바이트 | 빈 상자 완충재 |
| FCS(4B) | CRC-32 오류 검출 값 | 파손 검사 봉인 |
| MTU(1500B) | 한 프레임이 실을 수 있는 최대 Payload | 상자 최대 용량 |
| 점보 프레임 | MTU를 9000B까지 확장한 프레임 | 대형 화물 상자 |
| IFG(12B) | 프레임 사이 최소 간격(Interframe Gap) | 방송 사이 간격 |
| 802.1Q 태그(4B) | VLAN 식별자를 넣는 확장 필드 | 층/구역 라벨(019 참조) |

## 깊이 이해
- **배경·문제의식**: 초기 이더넷은 하나의 케이블을 여러 노드가 공유(CSMA/CD)했기에, 누구에게 가는지·누가 보냈는지·데이터가 온전한지를 프레임 규격으로 표준화할 필요가 있었음(L2 기본은 007 MAC 참조).
- **작동 원리(어떻게+왜)**: 송신 NIC이 Payload 앞에 목적지·출발지 MAC과 Type을 붙이고 끝에 CRC-32(FCS)를 계산해 넣음. 수신 NIC은 목적지 MAC이 자신·브로드캐스트인지 확인 후, 같은 CRC 계산으로 값이 일치하는지 검사해 다르면 폐기함 — 오류 프레임이 상위로 올라가 낭비되는 것을 막기 위함임.
- **비유**: 봉인된 택배. 겉면 주소로 분류하고, 봉인(FCS)이 뜯겨 있으면(값 불일치) 열지 않고 반송·폐기함.
- **구체 예시**: IPv4 패킷을 보낼 때 Type 필드에 0x0800을 넣어 수신 측이 IP 계층으로 올림. Payload가 20바이트뿐이면 26바이트 패딩을 더해 최소 프레임 크기 64바이트(헤더18+Payload46)를 맞춤 — 충돌 검출(CSMA/CD)이 성립하는 최소 길이 때문임.
- **흔한 오해·주의점**: 프리앰블·SFD·IFG는 물리 동기·간격용이라 통상 "프레임 크기 64~1518B" 계산에는 포함하지 않음. 또 Type/Length 필드는 값이 1500 이하면 길이(802.3 원형), 1536(0x0600) 이상이면 타입(Ethernet II)으로 해석됨.

## 연결 개념
- MAC 주소·OUI 구조(007 참조), CSMA/CD 매체 접근
- VLAN 태깅(IEEE 802.1Q, 019 참조)
- 상위 캡슐화: IP 패킷 -> 이더넷 프레임(001·002 참조)

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이더넷 프레임은 프리앰블·MAC 주소·Type·Payload·FCS로 구성된 L2 전송 단위로, IEEE 802.3이 필드 배치·길이를 규정함.
> 2. **가치**: 목적지 MAC 기반 스위칭과 CRC-32(FCS) 오류 검출로, 공유 매체에서 정확·무결한 프레임 전달을 보장함.
> 3. **판단 포인트**: 최소 64B·최대 1518B 제약의 이유(충돌 검출·MTU), Type/Length 이중 해석, 802.1Q 태그 확장이 핵심임.

## Ⅰ. 개요 및 필요성
- 정의: 이더넷 프레임은 헤더(MAC·Type)+Payload+트레일러(FCS)로 구성된 IEEE 802.3 표준 L2 전송 단위임.
- 배경: 공유 매체를 다수 노드가 함께 쓰므로 수신 대상·발신자·데이터 종류·무결성 표시가 필수임.
- 필요성: 목적지 MAC 기반 정확 분류와 CRC-32 오류 검출로 충돌·오배송·손상 프레임의 상위 전달을 차단할 필요 있음.

---

## Ⅱ. 구조 및 구성요소

```text
[Preamble 7B] -> [SFD 1B] -> [Dst MAC 6B] -> [Src MAC 6B] -> [Type/Length 2B]
   -> [Payload 46~1500B] -> [FCS 4B]   (프레임 뒤 IFG 12B)

크기: 헤더18B + Payload(46~1500) = 64~1518B  /  802.1Q 태그 시 +4B = 1522B
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Preamble+SFD(8B) | 클럭 동기·프레임 시작 지시 | 프레임 크기 계산서 제외 |
| Dst/Src MAC(각 6B) | 수신·발신 물리 주소 | OUI 3B+장치 ID 3B(007 참조) |
| Type/Length(2B) | 상위 프로토콜 지정 또는 길이 | ≥0x0600 타입, ≤1500 길이 |
| Payload(46~1500B) | 상위 계층 데이터, 부족 시 패딩 | 최소 46B로 64B 프레임 보장 |
| FCS(4B) | CRC-32 오류 검출 | 검출만·정정 불가 |

> 요약: 헤더의 MAC으로 분류하고 Type으로 상위 계층을 지정하며, 트레일러 FCS로 무결성을 검증하는 봉투 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
송신 NIC: Payload + MAC/Type 부착 -> CRC-32 계산해 FCS 삽입 -> Preamble/SFD 앞에 붙여 매체 송출
수신 NIC: 동기 획득 -> Dst MAC 확인(자신/브로드캐스트?) -> CRC 재계산 후 FCS 대조
   -> 일치: 상위 계층(Type 기준) 전달  /  불일치: 프레임 폐기
```

1. 송신 NIC이 Payload 앞에 목적지·출발지 MAC과 Type을 붙이고, 46B 미만이면 패딩을 채움.
2. 송신 NIC이 프레임 전체로 CRC-32를 계산해 FCS에 넣고, 프리앰블·SFD를 앞세워 매체로 내보냄.
3. 수신 NIC이 프리앰블로 동기를 잡고 목적지 MAC이 자신·브로드캐스트인지 확인해 아니면 무시함.
4. 수신 NIC이 CRC를 재계산해 FCS와 대조하여 일치 시 Type에 따라 상위 계층으로 올리고, 불일치 시 폐기함.

> 요약: 송신은 MAC·Type 부착 후 FCS 계산, 수신은 MAC 필터링 후 FCS 대조로 무결성을 검증해 손상 프레임을 상위로 올리지 않음.

---

## Ⅳ. 특징
- 최소 64B 제약: 충돌 검출(CSMA/CD)이 성립하려면 프레임이 최소 슬롯 타임만큼 매체를 점유해야 하므로 Payload 최소 46B가 강제됨.
- 최대 1518B 제약: Payload MTU 1500B로 상한을 둬 한 노드의 매체 독점과 버퍼 과다를 방지함.
- Type/Length 이중 해석: 1536(0x0600) 이상이면 타입(Ethernet II), 1500 이하면 길이(802.3)로 구분됨.
- FCS는 CRC-32 오류 검출만 수행하고 정정은 하지 않음(재전송은 상위 계층 몫).
- 점보 프레임: 데이터센터에서 MTU를 9000B로 늘려 헤더 오버헤드·CPU 인터럽트를 절감함.
- 802.1Q 태그(4B)로 VLAN·우선순위(PCP)를 실어 프레임을 1522B까지 확장함(019 참조).

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Ethernet II | IEEE 802.3(원형) |
|:---|:---|:---|
| 2B 필드 해석 | Type(상위 프로토콜, ≥0x0600) | Length(Payload 길이, ≤1500) |
| 상위 식별 방식 | Type 값으로 직접 지정 | LLC/SNAP 헤더로 별도 지정 |
| 실사용 | 현재 인터넷 대다수(IPv4=0x0800) | 초기 규격·일부 관리 프레임 |

> 요약: 오늘날 대부분 Ethernet II 방식으로 Type 필드가 상위 프로토콜을 직접 지정하며, 802.3 원형은 길이 표기+LLC/SNAP 구조로 제한적으로 남음.

- 리스크: 오류 프레임 다발 — 케이블 불량·전자기 간섭 — FCS 폐기율·CRC 에러 카운터 모니터링으로 대응함.
- 리스크: 런트/자이언트 프레임 — 64B 미만·1518B 초과 비정상 — 스위치 포트 통계 감시·불량 NIC 교체로 대응함.
- 지표: 프레임 오류율 — 목표 근사 0% — 스위치 CRC 에러·discards 카운터로 측정함.
- 지표: MTU 정합성 — 경로 전 구간 MTU 일치 — PMTUD·핑 DF 비트 테스트로 측정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. [장애 진단] 스위치 포트의 CRC 에러·런트·자이언트 카운터를 상시 수집해 케이블·NIC 물리 불량 구간을 조기 식별.
2. [성능 최적화] 스토리지·클러스터 백엔드망에 점보 프레임(MTU 9000B)을 전 구간 일관 적용해 헤더 오버헤드·인터럽트 절감.
3. [망 분할] 802.1Q 태깅으로 부서·서비스별 VLAN을 나누고 PCP로 우선순위를 부여해 브로드캐스트 도메인을 격리(019 참조).

**결론(2줄):**
- 기술사 판단: 범용 접속망은 표준 MTU 1500B로 호환성을 지키고, 데이터센터 백엔드처럼 대용량 전송이 지배적이면 점보 프레임을 전 구간 일관 적용함.
- 향후 방향: 산업·자율주행 영역에서는 이더넷 프레임 위에 시간 결정성을 더한 TSN(Time-Sensitive Networking, 104 참조)으로 실시간 전송 요구를 수용하는 방향으로 확장 중임.
