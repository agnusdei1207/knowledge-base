## Ⅰ. 개요
- **정의**: 1 ms 이하 왕복 지연으로 원격 촉각·운동감각 피드백을 실시간 전달하는 네트워크 기술임
- **배경/필요성**: 원격 수술·산업 로봇 제어 등에서 시각·청각만으로는 정밀 조작이 불가능하므로, 촉각 정보의 초저지연 전송이 요구됨
- **비유**: 전화가 목소리를 전달하듯, 촉각 인터넷은 손끝의 감각을 전달하는 통신임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 초저지연 네트워크의 활용 사례 이해 | RTT 1 ms + 신뢰성 99.999% 요구 | 단순 5G URLLC와의 차이(양방향 햅틱 루프) 구분 |

> 요약: 1 ms 이하 RTT로 촉각 피드백을 양방향 전달하는 초저지연 네트워크 기술임

## Ⅱ. 구성요소
```text
Master Domain          Network Domain          Slave Domain
+-----------+      +----------------+      +-----------+
| Operator  | ---> | Edge Cloud     | ---> | Teleop    |
| + Haptic  | <--- | (MEC/URLLC)    | <--- | Robot     |
| Device    |      +----------------+      +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Master Domain | 사용자가 햅틱 장치로 명령을 입력하는 조작 영역 | 조종석의 조종간 |
| Network Domain | 1 ms 이하 RTT를 보장하는 MEC 기반 전송 구간 | 신경계의 척수 반사 경로 |
| Slave Domain | 원격지에서 명령을 수행하고 촉각을 반환하는 실행 영역 | 로봇 팔의 손끝 |
| Haptic Codec | 촉각 신호를 압축·복원하는 부호화기 | 음성 코덱의 촉각 버전 |

> 요약: 마스터-네트워크-슬레이브 3개 도메인과 햅틱 코덱으로 구성됨

## Ⅲ. 절차
```text
조작 입력 --> 햅틱 부호화 --> 초저지연 전송 --> 원격 실행/피드백 반환
```
- 1단계: 사용자가 햅틱 장치로 힘·위치·속도 명령을 입력함
- 2단계: 햅틱 코덱이 촉각 데이터를 압축하여 패킷으로 생성함
- 3단계: MEC 에지 노드 경유로 1 ms 이하 왕복 지연을 보장하며 전송함
- 4단계: 슬레이브 로봇이 동작을 수행하고 촉각 피드백을 마스터로 반환함

> 요약: 입력-부호화-전송-피드백의 양방향 루프를 1 ms 이내에 완료함

## Ⅳ. 문제점
- 지연 편차: 네트워크 지터가 1 ms 이상이면 햅틱 루프가 불안정해져 제어 발산이 발생함
- 대역폭 부담: 촉각·영상·음성 멀티모달 동시 전송 시 수 Gbps 대역이 요구됨
- 안전성 확보 곤란: 통신 단절 시 원격 로봇의 즉시 안전 정지 메커니즘이 미비함

> 요약: 지터·대역폭·안전 정지 측면에서 기존 네트워크 대비 엄격한 요건이 존재함

## Ⅴ. 개선방안
1. 단기: 에지 캐싱과 예측 제어를 결합하여 지터 영향을 보상함
2. 중기: 햅틱 코덱의 압축률 향상으로 멀티모달 트래픽의 대역 요구를 절감함
3. 장기: 통신 두절 시 로컬 자율 제어로 전환하는 Fail-safe 아키텍처를 표준화함

> 요약: 지터 보상·코덱 효율·안전 정지 순으로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: 6G의 sub-ms 지연 목표와 결합하여 촉각 인터넷 상용화가 본격화될 전망임
- 기술사적 판단: 원격 의료·제조·재난 대응 분야에서 킬러 애플리케이션이 될 가능성이 높음
- 기술사 제언: 네트워크 QoS 설계 시 RTT 1 ms·신뢰성 99.999% 요건을 정량적으로 반영할 필요
