## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 계층별 통신 단절, 라우팅 경로 이상, 장비의 오픈 포트 및 세션 연결 상태를 실시간 진단하기 위해 OS에 기본 내장된 네트워크 유틸리티 명령어 모음 |
| **배경/필요성** | 복잡한 네트워크 장애 발생 시 가장 빠르고 직관적으로 1차 원인 구역 분리(Fault Isolation) 및 증상 진단 필요 |
| **출제 의도** | ICMP(Echo) 기반의 도달성 테스트 원리와 IP 헤더의 TTL을 응용한 경로 추적 메커니즘, OS 소켓 기반 연결 추적 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
|  Client  |       | Router   |       |  Server  |
| (Cmd CLI)| ----> | (Hop)    | ----> | (Target) |
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| ping (도달성) | ICMP Echo Request/Reply를 통해 대상 단말 생존 여부와 RTT 지연 속도 확인 | 수중 음파 탐지기 |
| traceroute | IP 헤더의 TTL(Time To Live) 값을 1부터 1씩 증가 발송하여 라우터 경로(Hop)를 순차 파악 | 헨젤과 그레텔 빵조각 |
| netstat (소켓) | 로컬 호스트의 열려 있는 리스닝 포트(LISTEN) 및 현재 성립된(ESTABLISHED) TCP 세션 상태 점검 | 건물 출입문 개방 현황판 |

> 요약: ICMP 프로토콜과 소켓 커널 정보 조회를 결합해 물리 단절부터 애플리케이션 연결 문제까지 신속 규명함

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 단말 핑  | -> | 경로 추적| -> | 소켓 확인| -> | 결함 격리|
+----------+    +----------+    +----------+    +----------+
```
1. 단말 핑: 대상 서버 IP로 ping 전송 후 응답(Reply) 실패 또는 Request Timed Out 발생 시 기본 통신 불능 상태 인지
2. 경로 추적: 통신 단절 구간 파악을 위해 traceroute 수행, TTL Expired 응답을 보내는 마지막 라우터 위치(Hop) 특정
3. 소켓 확인: 대상 서버 접속(SSH) 후 netstat/ss 명령어로 정상 서비스 데몬(Apache 등)이 예상 포트로 LISTEN 중인지 점검
4. 결함 격리: (네트워크 구간 단절 / 서버 방화벽 차단 / 애플리케이션 서비스 미구동) 등 최종 장애 책임 소재 파악 조치

> 요약: Ping으로 도달 검증, Traceroute로 끊긴 라우터 특정, Netstat으로 종단 서버 프로세스 연결 상태 진단 수행

## Ⅳ. 문제점
- 최근 보안 정책상 방화벽 및 라우터가 불필요한 ICMP 패킷을 전면 차단하여 정상 서버도 Ping 요청에 응답 거부 (오판 원인)
- 비대칭 라우팅(Asymmetric Routing) 환경에서 돌아오는 경로(Return Path)가 다르면 traceroute 결과 출력에 지연 및 별표(*) 오류 발생
- netstat 명령어는 초당 수만 건의 세션이 생성/소멸하는 고부하 웹 서버 수행 시 커널 부하 유발 및 출력 시간 과다 소요 (명령어 한계)

## Ⅴ. 개선방안
- [단기] ICMP 차단 환경 우회를 위해 대상 서버의 특정 개방 서비스 포트(TCP 80/443) 대상으로 tcping / telnet 도달 검증 수행
- [중기] 리눅스 환경에서 구형 netstat 명령어 사용을 중단하고 커널 친화적이고 압도적 고속인 ss 명령어 체계로 100% 전환
- [장기] 수동 트러블슈팅을 탈피하고 BFD(Bidirectional Forwarding Detection) 및 합성(Synthetic) 트랜잭션 기반 자동화 모니터링 시스템 구축

## Ⅵ. 전망
- 명령어 기반의 수동 점검 체계는 한계에 봉착하여, SDN 컨트롤러 연동 자동화된 경로 핑(Ping)과 텔레메트리로 대체될 전망임
