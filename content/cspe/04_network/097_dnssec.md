## Ⅰ. 개요
- **정의**: DNS 응답에 전자서명을 추가하여 위·변조를 검증하는 DNS 보안 확장 표준
- **배경/필요성**: DNS 프로토콜은 응답 인증 메커니즘이 없어 캐시 포이즈닝 공격에 취약함
- **비유**: 우편물(DNS 응답)에 봉인 도장(전자서명)을 찍어 수신자가 위조 여부를 확인하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DNS 무결성 보장 메커니즘 이해 | 서명 체인(KSK-ZSK-RRSIG-DS) | 기밀성은 제공하지 않음(DoH/DoT(098 참조)과 구분) |

> 요약: DNS 응답의 출처 인증과 무결성을 전자서명 체인으로 보장하는 확장임

## Ⅱ. 구성요소
```text
[Root] --DS--> [TLD] --DS--> [Zone] --RRSIG--> [Resolver] --> [Client]
  |              |              |
 KSK            KSK           ZSK
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| KSK (Key Signing Key) | ZSK를 서명하는 상위 신뢰 키 | 인감증명 발급 기관 |
| ZSK (Zone Signing Key) | 실제 DNS 레코드(RRSIG)를 서명하는 키 | 실무 담당자 도장 |
| RRSIG | DNS 레코드에 대한 전자서명 데이터 | 봉인 도장 자국 |
| DS (Delegation Signer) | 하위 존 KSK 해시를 상위 존에 등록하여 신뢰 체인을 연결 | 상위 기관의 위임장 |

> 요약: KSK-ZSK-RRSIG-DS로 루트부터 개별 존까지 신뢰 체인을 형성함

## Ⅲ. 절차
```text
키 생성 --> 존 서명 --> DS 등록 --> 검증 질의
```
- 1단계: 존 관리자가 KSK·ZSK 키쌍을 생성함
- 2단계: ZSK로 존 내 모든 레코드셋에 RRSIG를 생성하여 서명함
- 3단계: KSK의 해시(DS 레코드)를 상위 존에 등록하여 신뢰 체인을 연결함
- 4단계: 검증 리졸버가 루트부터 DS-DNSKEY-RRSIG를 순차 검증하여 응답 무결성을 확인함

> 요약: 키생성-존서명-DS등록-검증 4단계로 DNS 응답 무결성을 보장함

## Ⅳ. 문제점
- 키 관리 복잡성: KSK/ZSK 롤오버 절차가 복잡하여 운영 실수 시 서비스 장애 발생
- 응답 크기 증가: RRSIG·DNSKEY 레코드 추가로 UDP 응답이 커져 단편화 발생
- 보급률 저조: 전체 도메인 중 DNSSEC 적용 비율이 낮아 검증 효과가 제한적임

> 요약: 키관리·응답크기·보급률이 DNSSEC 확산의 주요 장벽임

## Ⅴ. 개선방안
1. 단기: 자동 키 롤오버 도구(knot-dnssec 등) 도입으로 운영 부담 감소
2. 중기: DNS 쿠키·EDNS0 최적화로 대용량 응답 처리 안정화
3. 장기: 레지스트리·레지스트라 단계에서 DNSSEC 자동 활성화 정책 추진

> 요약: 자동롤오버-응답최적화-자동활성화 순으로 보급 장벽을 해소함

## Ⅵ. 전망
- 발전 방향: DoH/DoT(098 참조)와 결합하여 DNS 무결성+기밀성 동시 확보 추세
- 기술사적 판단: 제로트러스트 환경에서 DNS 계층 신뢰 확보의 기반 기술로 중요성 증가
- 기술사 제언: DNSSEC 도입 시 키 관리 자동화와 모니터링 체계를 함께 설계할 필요
