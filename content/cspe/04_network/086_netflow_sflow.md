## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 라우터/스위치를 통과하는 트래픽 흐름(Flow)의 메타데이터나 샘플링된 패킷을 중앙 수집기(Collector)로 전송하여 트래픽 유형 및 사용량을 분석하는 기술 |
| **배경/필요성** | SNMP가 알려주지 못하는 '누가(Who)', '무엇을(What)', '어디로(Where)' 트래픽을 유발했는지에 대한 심층적 L3/L4/L7 가시성 필요 |
| **출제 의도** | 소프트웨어 캐시 기반 플로우 분석(NetFlow)과 하드웨어 기반 패킷 샘플링(sFlow) 기술 간의 동작 원리 및 부하 차이 평가 |

## Ⅱ. 구성요소
```text
+----------+       +----------+       +----------+
| End User |       |  Router  |       | Collector|
| (Traffic)| ====> | (Sensor) | ----> | (Analyzer|
+----------+       +----------+       +----------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| Flow (흐름) | 동일한 출발/도착 IP, 포트번호, 프로토콜 등을 지닌 단방향 패킷들의 연속된 논리적 집합 | 차량 이동 행렬 |
| NetFlow (Cisco) | 장비 내부 캐시(Cache)에 개별 플로우의 누적 통계(바이트/패킷 수)를 저장 후 전송 (정밀 분석) | 정밀 고속도로 톨게이트 집계 |
| sFlow (sInMon) | 캐시 없이 L2 스위치 칩셋(ASIC)에서 N번째 패킷을 단순 샘플링 추출하여 서버로 즉시 전송 (부하 최소) | 무작위 표본 설문조사 |

> 요약: 전체 패킷을 복사(Mirror)하지 않고 핵심 메타데이터나 표본만 추출하여 대규모 트래픽 분석에 최적화됨

## Ⅲ. 절차
```text
+----------+    +----------+    +----------+    +----------+
| 패킷 인입| -> | 캐시 기록| -> | 조건 만료| -> | 서버 전송|
+----------+    +----------+    +----------+    +----------+
```
1. 패킷 인입: 10G 이상의 대용량 트래픽이 라우터나 핵심 스위치의 인터페이스 통과 시작
2. 캐시 기록: (NetFlow) 5-Tuple(IP/Port/Proto)을 기준으로 동일 플로우 식별 후 캐시 메모리에 누적 바이트 카운트 증가
3. 조건 만료: 플로우 통신이 종료되거나(FIN/RST), 최대 타이머(Active/Inactive) 초과 시 캐시 항목 익스포트(Export) 대상 지정
4. 서버 전송: 라우터가 수집된 다수의 플로우 요약 데이터를 단일 UDP 데이터그램 묶어 전문 Collector 서버로 발송

> 요약: 고속 스위칭 트래픽을 요약 통계(NetFlow)나 표본(sFlow) 형태로 변환 후 분석기로 전달함

## Ⅳ. 문제점
- NetFlow는 소프트웨어 캐시 유지 및 조회를 위한 라우터 CPU, Memory 점유율이 높아 통신 지연 유발 위험 안고 있음
- 초대형 DDoS 발생(SYN Flood) 시 고유 플로우가 순식간에 수백만 개 생성되어 라우터 캐시 고갈 및 장비 멈춤 장애 유발
- sFlow는 1/1000 단위 등의 단순 샘플링 방식이므로 짧고 간헐적인 해킹(마이크로 버스트) 통신 추적 탐지에 맹점 발생

## Ⅴ. 개선방안
- [단기] 장비 부하 방지를 위해 Sampled NetFlow 기법을 적용하여 100개 중 1개 플로우만 선택적 캐시 생성 통제
- [중기] 엔터프라이즈 코어 스위치에는 부하가 적은 하드웨어 sFlow, 라우터 경계망에는 정밀한 NetFlow V9 적용 (이원화)
- [장기] 빅데이터 기반 NTA/NDR(네트워크 위협 탐지 및 대응) 솔루션 도입으로 수집된 플로우 연계 실시간 악성 행위 AI 분석 구현

## Ⅵ. 전망
- 단순 용량 산정을 넘어 인공지능 기반 악성 트래픽 사전 이상 탐지 모델(AI-NDR) 구축을 위한 핵심 데이터 셋으로 역할이 커질 것임
