## Ⅰ. 개요
- **정의**: CPU, 메모리, 배터리 자원이 극도로 제한된 소형 IoT 기기들이 불안정한 네트워크 환경에서 데이터를 효율적으로 교환하기 위한 경량 통신 프로토콜임.
- **배경/필요성**: 기존 무거운 HTTP 프로토콜의 방대한 헤더와 오버헤드로 인해 저전력 센서 네트워크(LPWAN 등)에 적용 불가능한 문제 해결.
- **출제 의도**: MQTT(Pub/Sub, TCP 기반)와 CoAP(Req/Res, UDP 기반)의 통신 아키텍처 및 QoS(Quality of Service) 보장 메커니즘 차이점 파악.

## Ⅱ. 구성요소
```text
[ MQTT Architecture ]           [ CoAP Architecture ]
+--------+                      +--------+
| Sensor | (Publisher)          | Client | (IoT Node)
+--------+                      +--------+
   | Publish (TCP)                 | Request (UDP/DTLS)
+--------+                      +--------+
| Broker | (Central Hub)        | Server | (Gateway/Cloud)
+--------+                      +--------+
   | Push                          | Response
+--------+                      +--------+
|  App   | (Subscriber)         | Client |
+--------+                      +--------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| MQTT Broker | 메시지 전송(Publish)과 수신(Subscribe) 사이에서 데이터를 주제(Topic)별로 중계하는 중앙 서버 | 우체국 분류 센터 |
| MQTT QoS | 전송 신뢰성 등급 (QoS 0: 최대 한 번, QoS 1: 최소 한 번, QoS 2: 정확히 한 번) | 우편물 배송 확인 옵션 |
| CoAP | 제한된 환경을 위해 HTTP의 RESTful(GET/POST 등) 구조를 경량화하여 UDP 위에서 동작하는 프로토콜 | 속달용 미니 소포 |
> 요약: MQTT는 브로커 기반의 비동기 중앙 배포 모델이고, CoAP는 경량화된 HTTP 스타일의 1:1 요청/응답 모델임.

## Ⅲ. 절차
```text
+-----------+   +-------------+   +-------------+   +-----------+
| 연결 확립 |-> | 토픽 구독   |-> | 데이터발행  |-> | 메시지분배|
+-----------+   +-------------+   +-------------+   +-----------+
```
1. **연결 확립 (MQTT)**: IoT 단말이 TCP 연결을 맺고 브로커에 CONNECT 메시지를 보내 세션을 시작함.
2. **토픽 구독**: 수신 측(예: 모니터링 앱)이 브로커에 특정 주제(예: 'sensor/temp')를 Subscribe(구독) 요청함.
3. **데이터 발행**: 온도 센서(Publisher)가 주기적으로 측정한 데이터를 해당 주제(Topic)로 브로커에 Publish 함.
4. **메시지 분배**: 브로커는 해당 주제를 구독 중인 모든 클라이언트에게 수신한 메시지를 비동기적으로 푸시 전달함.
> 요약: 생산자는 토픽에 던지고, 소비자는 토픽에서 받아가는 구조로, 양측은 서로의 존재를 알 필요가 없음(디커플링).

## Ⅳ. 문제점
- **보안 오버헤드**: 데이터 보호를 위해 TLS/DTLS 암호화를 적용하면 초기 핸드쉐이크 및 패킷 크기가 커져 배터리 소모 급증.
- **단일 장애점 (MQTT)**: 모든 메시지가 브로커를 통과하므로, 브로커 장애나 병목 시 전체 IoT 시스템 마비.
- **신뢰성 저하 (CoAP)**: UDP 기반이므로 네트워크 환경이 열악할 경우 패킷 손실이 잦아 앱 계층에서 재전송 로직을 별도 구현해야 함.

## Ⅴ. 개선방안
- **경량 보안 적용**: IoT에 특화된 경량 암호화 알고리즘이나 사전 공유 키(PSK) 방식의 DTLS 적용으로 암호화 부하 완화 (단기).
- **브로커 이중화**: MQTT 브로커를 클러스터링(Active-Active)으로 구성하여 고가용성 및 트래픽 로드밸런싱 확보 (중기).
- **엣지 컴퓨팅 연동**: 클라우드 브로커로 데이터를 보내기 전 엣지 게이트웨이에서 로컬 브로커를 운영해 트래픽 필터링 및 지연 감소 (장기).

## Ⅵ. 전망
- 스마트 홈, 스마트 팩토리, 커넥티드 카 환경에서 데이터 파이프라인의 표준 수집 프로토콜(주로 MQTT)로 확고히 자리잡음.
- 향후 5G/6G 초저지연 통신 인프라와 결합되어 실시간 자율 제어 및 로보틱스 분야로 응용 영역이 크게 확장될 것임.
