## 미리 알고가기

- SSE는 SASE에서 네트워크 연결 기능을 뺀 보안 서비스 묶음임
- SWG는 웹 접속을 검사하는 보안 게이트웨이임
- DLP는 민감 정보가 외부로 빠져나가지 않게 막는 통제 기능임
- ZTNA는 허가된 애플리케이션만 연결하는 원격 접속 방식임

## Ⅰ. 개요

- **정의/개념**: SSE는 SWG와 CASB와 ZTNA와 DLP 같은 보안 기능을 클라우드 엣지에서 제공해 사용자와 SaaS와 내부 애플리케이션 접근을 통합 통제하는 보안 아키텍처임
- **배경/필요성**: 모든 조직이 광역망부터 다시 바꾸기는 어려우므로, 기존 네트워크는 두되 사용자 접속과 데이터 통제를 먼저 현대화할 보안 중심 구조가 필요해짐

## Ⅱ. 특징

- 네트워크 재구축 없이 보안 기능부터 단계적으로 도입할 수 있음
- 웹, SaaS, 내부 앱 접근을 사용자 기준으로 통합 관리하기 쉬움
- 클라우드 제공 방식이라 지점 증설보다 정책 표준화가 더 중요함
- 연결 기능이 빠진 만큼 광역망 최적화는 별도 구조와 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | SSE | SASE |
|:---|:---|:---|
| 포함 범위 | 보안 서비스 중심임 | 보안과 SD-WAN을 함께 포함함 |
| 도입 출발점 | 사용자 접속 통제와 SaaS 보안에 적합함 | 지사 연결과 보안을 함께 바꿀 때 적합함 |
| 네트워크 기능 | 광역망 경로 최적화 기능은 없음 | 경로 선택과 회선 활용을 함께 다룸 |
| 운영 초점 | 정책 통합과 데이터 보호에 집중함 | 정책 통합과 경로 최적화를 함께 봄 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 단말 | 웹과 SaaS와 내부 앱 접속을 시작함 |
| 인증 체계 | 사용자와 기기 상태를 확인함 |
| SSE 정책 엔진 | 서비스별 접근과 데이터 정책을 판단함 |
| SWG·CASB·ZTNA·DLP | 웹 통제, SaaS 통제, 원격 접속, 데이터 유출 방지를 수행함 |
| 로그·분석 기능 | 정책 위반과 이상 행위를 기록함 |

```text
+--------+    신원 확인    +------------+    정책 적용    +----------------+
| 사용자   | -----------> | SSE 엔진      | -------------> | 웹·SaaS·내부 앱 |
+--------+               +------------+                +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[접속 시도] -> [신원·기기 확인] -> [서비스별 정책 판단] -> [허용·차단] -> [로그 분석]
```

1. **접속 시도**: 사용자가 웹이나 SaaS나 내부 앱 접속을 요청함
2. **신원·기기 확인**: 인증과 단말 상태를 확인함
3. **서비스별 정책 판단**: 어떤 기능으로 검사할지 결정함
4. **허용·차단**: 허용, 차단, 격리, 경고 같은 동작을 수행함
5. **로그 분석**: 이상 행위를 기록하고 대응 흐름에 넘김

## Ⅵ. 실무 적용 및 유의점

1. SaaS와 원격 사용자가 먼저 문제인 조직은 SSE로 빠르게 가시성과 통제를 얻을 수 있지만 기존 프록시와 정책이 중복되면 운영이 꼬이므로 서비스 분류와 사용자 그룹 정책을 먼저 정리하고 우회 접속 건수와 정책 충돌 건수를 같이 확인함
2. 내부 앱 보호까지 SSE에 얹을 때는 인증 체계와 앱 연결 구조가 맞물려야 하므로 ZTNA 연계와 데이터 분류 정책을 함께 점검하고 접속 성공률과 민감 정보 차단 정확도를 계속 봐야 함

## Ⅶ. 결론

SSE는 네트워크 전체를 바꾸기 전에 사용자와 데이터 중심 보안을 먼저 정비할 때 효과가 큰 보안 서비스 묶음임.
