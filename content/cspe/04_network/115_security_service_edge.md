# 📖 【암기용】 개념 완전 이해

> 목적: SSE를 SASE 중 보안 기능 묶음으로 이해하고, SWG·CASB·ZTNA·DLP의 역할을 구분하게 만든다.

## 한눈에
- **개요**: SSE는 네트워크 연결 기능을 제외하고 SWG, CASB, ZTNA, DLP 같은 보안 서비스를 클라우드 엣지에서 제공하는 모델이다.
- **왜 필요한가**: 사용자가 본사망을 거치지 않고 SaaS와 인터넷에 직접 접속하면 기존 보안 장비의 통제 지점을 우회한다.
- **핵심 직관**: 도로를 새로 까는 SD-WAN은 빼고, 검문·신원확인·반출검사만 지역 검문소에서 처리하는 구조다.

## 깊이 이해
- **배경·문제의식**: SaaS, 모바일, 재택근무 환경에서는 웹 접속, 클라우드 앱 사용, 사내 앱 접근이 분산되어 통합 정책이 필요하다.
- **작동 원리**: 사용자 트래픽은 에이전트, PAC, 터널, API 연동을 통해 SSE PoP로 전달되고, PoP는 웹, SaaS, 사내 앱, 데이터 정책을 평가한다.
- **비유**: 공항에서 탑승구별로 보안검색을 반복하지 않고 중앙 검색대에서 신원, 수하물, 반출품을 한 번에 확인하는 방식과 같다.
- **구체 예시**: 사용자가 Google Drive에 주민등록번호 파일을 업로드하면 CASB API와 DLP 정책이 탐지하고, 미승인 앱 접속은 SWG가 차단한다.
- **흔한 오해·주의점**: SSE는 SD-WAN 품질 제어를 포함하지 않는다. 회선 경로 제어까지 필요하면 SASE 전체 구조를 검토한다.

## 연결 개념
- SASE - SSE에 SD-WAN 기능을 결합한 통합 아키텍처
- CASB - SaaS 사용 가시성과 데이터 통제
- SWG/ZTNA - 웹 보안과 사내 앱 접근 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: SSE 답안은 SASE와의 차이를 먼저 고정하고, 보안 기능별 통제 대상을 구분한다.
> 핵심: SWG는 웹, CASB는 SaaS, ZTNA는 사내 앱, DLP는 데이터 흐름을 통제한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SSE는 클라우드 엣지에서 웹·SaaS·사내 앱·데이터 접근 보안을 통합 제공하는 보안 서비스 묶음이다.
> 2. **가치**: 사용자가 어디서 접속해도 동일한 IdP, 단말 상태, DLP, 위협 탐지 정책을 적용한다.
> 3. **판단 포인트**: SD-WAN이 필요한지, 보안 기능 통합만 필요한지에 따라 SSE와 SASE를 구분한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SSE 범위 이해 확인 | SWG, CASB, ZTNA, DLP, RBI | SD-WAN을 SSE 기능으로 포함 |
| 클라우드 보안 통제 확인 | API 방식, Proxy 방식, TLS 검사 | CASB와 SWG 역할 혼동 |
| 운영 지표 제시 확인 | DLP 탐지, Shadow IT, 정책 오탐 | 기능 나열만 하고 증적 누락 |

> 요약: SSE 문제는 SASE에서 네트워크 기능을 제외한 보안 통제면을 설명하는 문제이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 클라우드형 보안 엣지
- 배경: 재택·모바일 사용자가 웹과 SaaS에 직접 접속해 기존 프록시와 방화벽을 우회함.
- 필요성: SWG, CASB, ZTNA, DLP 정책을 사용자·단말·앱 단위로 일관 적용해야 함.
- 판단 기준: SD-WAN 경로 제어가 필요하면 SASE, 보안 서비스 통합만 필요하면 SSE를 검토함.

---

## Ⅱ. 구조 및 구성요소

```text
User/Device -> SSE PoP -> Identity/Device Check
                         -> SWG for Web
                         -> CASB for SaaS
                         -> ZTNA for Private App
                         -> DLP/Threat Inspection -> Log/SIEM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SWG | 웹 URL, 악성코드, 파일 다운로드를 검사 | TLS 검사 예외와 인증서 관리 필요 |
| CASB | SaaS API/Proxy로 사용 행위와 데이터를 통제 | Shadow IT 탐지, DLP, 권한 점검 |
| ZTNA | 사내 앱 접근을 신원·단말 정책으로 허가 | VPN 대체 또는 공존 대상 식별 |
| DLP | 개인정보·영업비밀 반출을 탐지 | 정규식, EDM, OCR 정책 품질 관리 |
| RBI | 위험 웹 콘텐츠를 격리 브라우저에서 실행 | 고위험 카테고리와 관리자 계정에 적용 |

> 요약: SSE는 웹, SaaS, 사내 앱, 데이터 흐름을 PoP에서 통합 검사하고 로그를 남긴다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 트래픽 -> SSE PoP 접속 -> 신원/단말 확인
-> 웹/SaaS/앱 분기 -> 정책 검사 -> 허용/차단/격리 -> 로그 전송
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 에이전트, PAC, 터널, API로 트래픽을 SSE로 유도 | 우회 트래픽 비율, 에이전트 상태 |
| 2 | IdP와 단말 상태로 사용자 맥락을 확인 | MFA, EDR, OS 패치 |
| 3 | 목적지에 따라 SWG, CASB, ZTNA 정책을 선택 | URL, SaaS 앱 ID, private app ID |
| 4 | DLP와 위협 검사 결과에 따라 허용·차단·격리 | 정책 룰 ID, 탐지 근거 |
| 5 | 결과 로그를 SIEM/SOAR로 전송 | 사용자 ID, 파일 해시, 정책 결과 |

> 요약: SSE는 트래픽을 PoP로 모은 뒤 신원과 목적지에 따라 보안 서비스를 선택 적용한다.

## Ⅳ. 특징

| 구분 | 기존 보안 프록시 | SSE 적용 | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 적용 위치 | 데이터센터 장비 | 클라우드 PoP | 사용자 근접 PoP, TLS 검사 |
| 보호 대상 | 웹 중심 | 웹, SaaS, 사내 앱, 데이터 | SWG, CASB, ZTNA, DLP |
| 정책 단위 | IP, URL, 포트 | 사용자, 단말, 앱, 데이터 | IdP, device posture |
| 로그 | 장비별 분산 | 공통 사용자 ID 기반 통합 | SIEM schema, SOAR playbook |

> 요약: SSE는 분산 사용자의 보안 정책을 클라우드 PoP에서 통합 적용한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SSE | SASE | 선택 기준 |
|:---|:---|:---|:---|
| 범위 | 보안 서비스 중심 | SD-WAN+보안 통합 | 회선 경로 제어 필요성 |
| 도입 대상 | 사용자, SaaS, 웹, 앱 접근 | 지사 WAN과 보안 동시 전환 | 지사 회선 구조 |
| 핵심 지표 | DLP, 웹 차단, ZTNA 실패 | 지연, 회선 품질, 보안 탐지 | 네트워크 품질 요구 |
| 조직 책임 | 보안팀 중심 | 네트워크팀+보안팀 공동 | 운영 조직 구조 |

> 요약: 회선 제어가 범위 밖이면 SSE를 먼저 적용하고, WAN 전환까지 포함하면 SASE로 확장한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 우회 접속 | 에이전트 비활성, 개인 브라우저 사용 | Always-on 터널, DNS 정책 통제 | 비관리 트래픽 비율 |
| TLS 검사 충돌 | 인증서 핀닝, 민감 사이트 복호화 | 카테고리별 예외, 법무 검토 | 예외 도메인 수 |
| DLP 오탐 | 정규식 품질 부족 | EDM, 파일 지문, 승인 워크플로 | 오탐률, 승인 소요 시간 |
| SaaS 가시성 누락 | API 연동 미설정 | 주요 SaaS API 커넥터 등록 | API 수집 성공률 |

> 요약: SSE 운영 리스크는 우회, TLS 예외, DLP 오탐, SaaS API 수집에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 웹 통제 | 악성 URL 차단 정책 100% 적용 | SWG 로그, 테스트 URL |
| SaaS 가시성 | 승인 SaaS API 연동률 95% 이상 | CASB 대시보드 |
| 데이터 통제 | 개인정보 DLP 오탐률 5% 이하 | DLP 이벤트 샘플링 |
| 대응 시간 | 정책 위반 MTTR 30분 이하 | SOAR 티켓, 처리 이력 |

> 요약: SSE 성과는 웹 통제, SaaS 가시성, 데이터 통제, 대응 시간으로 검증한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 사용자 트래픽을 에이전트와 PAC로 SSE PoP에 유도하고, 우회 DNS와 비관리 브라우저 접속을 정책으로 차단함.
2. SWG URL 정책, CASB API/Proxy 정책, ZTNA private app 정책, DLP 분류 체계를 공통 사용자 ID 기준으로 설계함.
3. SSE 이벤트를 SIEM/SOAR에 연동하고, 개인정보 업로드, 비승인 SaaS, 악성 URL 접속을 playbook으로 처리함.

**결론 (2줄):**
- 기술사 판단: 보안 통제면 통합이 목표이면 SSE, 지사 WAN 품질 제어까지 목표이면 SASE를 선택함.
- 향후 방향: SSE는 CASB·SWG·ZTNA 로그를 UEBA와 SOAR로 연결해 사용자 행위 기반 대응 구조로 확장됨.
