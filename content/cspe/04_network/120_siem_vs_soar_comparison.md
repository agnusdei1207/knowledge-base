## 미리 알고가기

- SIEM은 로그를 모아 분석하고 경보를 만드는 관제 플랫폼임
- SOAR는 경보를 받아 대응 절차를 자동 실행하는 대응 플랫폼임
- 보안 관제 센터는 경보를 분석하고 사건을 처리하는 운영 조직임
- 경보 품질은 실제 위협을 잘 골라내는 정도를 뜻함

## Ⅰ. 개요

- **정의/개념**: SIEM과 SOAR 비교는 탐지를 중심으로 보는 플랫폼과 대응 자동화를 중심으로 보는 플랫폼의 역할 경계를 구분하는 운영 구조 판단임
- **배경/필요성**: 조직이 탐지 도구와 대응 도구를 같은 것으로 오해하면 투자 우선순위와 운영 체계가 꼬이므로, 무엇이 경보를 만들고 무엇이 조치를 실행하는지 분명히 나눠야 함

## Ⅱ. 특징

- SIEM은 로그 수집과 상관분석과 경보 생성에 강함
- SOAR는 경보 이후 조사 보강과 조치 자동화에 강함
- 둘은 대체 관계보다 연계 관계에 가까움
- 탐지 기준이 흔들린 상태에서 SOAR만 먼저 키우면 자동화 품질이 낮아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | SIEM | SOAR |
|:---|:---|:---|
| 주된 역할 | 로그를 분석해 위협 경보를 만듦 | 경보를 받아 절차대로 대응함 |
| 입력 데이터 | 다양한 시스템과 장비 로그임 | SIEM 경보와 위협 정보와 자산 정보임 |
| 산출 결과 | 경보, 탐지 규칙, 조사 단서임 | 차단 조치, 티켓, 대응 기록임 |
| 운영 초점 | 탐지 정확도와 관제 가시성임 | 대응 속도와 절차 표준화임 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 로그 원천 | SIEM이 수집하는 기본 데이터임 |
| SIEM | 로그를 정규화하고 상관분석해 경보를 만듦 |
| SOAR | 경보를 받아 정보 보강과 자동 조치를 수행함 |
| 보안 도구 | SOAR가 실제 차단과 격리를 실행하는 대상임 |
| 분석가 | 경보 검증과 예외 판단을 담당함 |

```text
[로그 원천] -> [SIEM] -> [경보] -> [SOAR] -> [보안 도구·티켓]
```

## Ⅴ. 원리 및 절차 흐름도

```text
[로그 수집] -> [탐지] -> [경보 전달] -> [자동 대응] -> [사건 종료]
```

1. **로그 수집**: 여러 자산에서 이벤트를 모음
2. **탐지**: SIEM이 상관분석으로 경보를 만듦
3. **경보 전달**: SOAR에 대응이 필요한 경보를 넘김
4. **자동 대응**: 정보 보강, 차단, 티켓 발행을 수행함
5. **사건 종료**: 분석가가 결과를 검토하고 종료함

## Ⅵ. 실무 적용 및 유의점

1. 관제 체계가 약한 조직은 SIEM으로 로그 구조와 탐지 시나리오를 먼저 안정화한 뒤 SOAR를 얹는 편이 낫고 경보 정확도와 평균 탐지 시간과 미조치 경보 적체를 먼저 확인해야 함
2. 대응 자동화를 늘릴 때는 경보 등급과 승인 단계를 함께 정리해야 하므로 자동 조치 비율과 평균 대응 시간과 오차 차단 건수를 같이 보며 범위를 넓혀야 함

## Ⅶ. 결론

SIEM과 SOAR의 차이는 수집과 자동화의 차이가 아니라 탐지를 담당할지 대응을 담당할지라는 운영 역할의 차이에 있음.
