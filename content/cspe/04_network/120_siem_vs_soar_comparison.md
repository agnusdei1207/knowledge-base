# 📖 【암기용】 개념 완전 이해

> 목적: SIEM과 SOAR를 탐지와 대응의 역할 분담으로 이해하고, 연계 구조를 답안에 쓸 수 있게 만든다.

## 한눈에
- **개요**: SIEM은 로그를 모아 탐지하고, SOAR는 탐지된 경보를 절차화해 대응한다.
- **왜 필요한가**: 경보를 발견하는 것과 실제 계정 잠금, 단말 격리, 티켓 보고를 완료하는 것은 다른 운영 단계다.
- **핵심 직관**: SIEM은 화재 감지기와 관제 화면이고, SOAR는 신고, 출동, 통제, 보고를 실행하는 비상 대응 매뉴얼이다.

## 깊이 이해
- **배경·문제의식**: 관제센터는 로그 폭증과 경보 피로도, 반복 대응 작업 때문에 탐지와 대응을 분리해 최적화해야 한다.
- **작동 원리**: SIEM은 수집·정규화·상관분석으로 경보를 만들고, SOAR는 경보를 Case로 받아 증거 수집, 승인, 차단, 보고를 playbook으로 수행한다.
- **비유**: 병원에서 진단 장비가 이상 수치를 알려주면, 의료진이 표준 프로토콜에 따라 검사·처치·기록을 수행하는 관계와 같다.
- **구체 예시**: SIEM이 VPN 해외 로그인과 AD 실패 로그를 묶어 경보를 만들면, SOAR는 사용자 확인, 계정 잠금 승인, EDR 격리, 티켓 보고를 실행한다.
- **흔한 오해·주의점**: SOAR가 SIEM을 대체하지 않는다. 탐지 품질은 SIEM 로그와 룰에 의존하고, SOAR는 대응 절차 품질에 의존한다.

## 연결 개념
- 융합 보안 관제 - SIEM, SOAR, EDR, NDR, TI를 통합 운영
- MTTD/MTTR - 탐지 시간과 대응 시간의 분리 지표
- Playbook - SOAR 대응 자동화의 실행 단위

# 📝 【답안용】 시험 답안 템플릿

> 목적: 비교 답안은 SIEM과 SOAR의 역할, 입력, 출력, 지표, 연계 순서를 명확히 나눠야 한다.
> 핵심: SIEM은 MTTD 중심, SOAR는 MTTR 중심이며 둘은 대체가 아니라 연계 관계다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIEM은 로그 기반 탐지 플랫폼이고, SOAR는 경보 기반 대응 자동화 플랫폼이다.
> 2. **가치**: SIEM은 공격 징후를 찾고, SOAR는 표준 절차로 조사·차단·보고를 수행해 관제 시간을 줄인다.
> 3. **판단 포인트**: 로그 커버리지와 correlation 품질은 SIEM 지표, playbook 성공률과 MTTR은 SOAR 지표로 분리한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 탐지와 대응 역할 구분 확인 | SIEM=수집·상관분석, SOAR=playbook·조치 | SOAR를 SIEM의 상위 버전으로 설명 |
| 연계 구조 이해 확인 | Alert -> Case -> Enrichment -> Action | 입력·출력 흐름 누락 |
| 지표 기반 운영 판단 확인 | MTTD, MTTR, 오탐률, 자동화율 | 같은 지표로 두 기술 평가 |

> 요약: 이 문제는 SIEM과 SOAR를 대체 관계가 아니라 탐지와 대응의 연계 관계로 설명해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: SIEM은 탐지, SOAR는 대응
- 배경: 보안 관제는 경보 발견 후 조사·승인·조치·보고까지 완료해야 종료됨.
- 필요성: SIEM correlation으로 MTTD를 줄이고, SOAR playbook으로 MTTR을 줄여야 함.
- 판단 기준: 로그 탐지 공백은 SIEM 개선, 반복 대응 병목은 SOAR 연계를 우선함.

---

## Ⅱ. 구조 및 구성요소

```text
Security Logs -> SIEM Collector -> Normalization -> Correlation -> Alert
Alert -> SOAR Case -> Enrichment -> Approval -> Action -> Report
Action Result -> SIEM/SOAR Feedback -> Rule/Playbook Tuning
```

| 구성요소 | SIEM 역할 | SOAR 역할 |
|:---|:---|:---|
| 입력 | 방화벽, VPN, AD, EDR, Cloud 로그 | SIEM 경보, EDR 경보, 메일 신고 |
| 처리 | 파싱, 정규화, 상관분석, UEBA | 사건 생성, 증거 수집, 승인, 조치 |
| 출력 | 경보, 대시보드, 감사 리포트 | 티켓, 차단, 격리, 처리 보고 |
| 지표 | MTTD, EPS, 오탐률, 로그 커버리지 | MTTR, 자동화율, playbook 성공률 |
| 운영자 | 탐지 룰 엔지니어, 관제 분석가 | 대응 자동화 엔지니어, 사고 담당자 |

> 요약: SIEM은 경보를 만들고 SOAR는 경보를 사건으로 처리하며, 결과는 다시 룰과 playbook 개선에 사용된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그 발생 -> SIEM 수집/정규화 -> correlation 경보
-> SOAR Case 생성 -> 증거 수집 -> 승인/자동 조치 -> 보고 -> 튜닝
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | SIEM이 다중 로그를 수집하고 공통 필드로 정규화 | 로그 누락률, 파서 오류 |
| 2 | correlation과 UEBA로 공격 시나리오 경보 생성 | MTTD, 룰 정확도, 오탐률 |
| 3 | SOAR가 경보를 Case로 변환하고 중복을 병합 | Case 생성 시간, 중복률 |
| 4 | playbook이 TI 조회, 자산 확인, 승인, 조치를 수행 | API 응답, 승인 이력 |
| 5 | 처리 결과로 SIEM 룰과 SOAR playbook을 튜닝 | MTTR, 성공률, 재발률 |

> 요약: 관제 흐름은 SIEM의 탐지 결과를 SOAR가 대응 절차로 실행하고, 결과를 다시 탐지·대응 품질 개선에 반영한다.

---

## Ⅳ. 특징

| 구분 | SIEM | SOAR | 수치·기술 포인트 |
|:---|:---|:---|:---|
| 주목적 | 탐지와 가시성 | 대응 자동화와 사건 관리 | MTTD vs MTTR |
| 핵심 기능 | 로그 수집, 정규화, correlation | playbook, connector, approval | MITRE ATT&CK, API action |
| 주요 산출물 | Alert, dashboard, report | Case, ticket, action result | audit trail |
| 한계 | 경보 후 조치 자동화 부족 | 탐지 품질은 외부 경보에 의존 | 오탐률, playbook 실패율 |

> 요약: SIEM은 경보 품질, SOAR는 대응 품질이 핵심이며 두 기술의 지표를 분리해야 한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SIEM 우선 개선 | SOAR 우선 도입 | 선택 기준 |
|:---|:---|:---|:---|
| 현재 문제 | 탐지 공백, 로그 누락 | 경보 처리 지연, 반복 작업 | MTTD와 MTTR 병목 |
| 데이터 조건 | 로그 소스와 파서 필요 | SIEM 경보와 API 도구 필요 | 데이터 품질과 연동 가능성 |
| 인력 역량 | 룰 개발, 로그 분석 | playbook 설계, 자동화 운영 | 조직 역할 분리 |
| 성과 지표 | 로그 커버리지, 오탐률 | 자동화율, 조치 성공률 | 월간 관제 리포트 |

> 요약: 탐지가 안 되면 SIEM을 먼저 개선하고, 탐지 후 처리가 늦으면 SOAR를 도입한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 나쁜 경보 자동화 | SIEM 오탐을 SOAR가 그대로 조치 | 고위험 조치 승인, 룰 품질 개선 | 오조치 건수 |
| 연동 실패 | API 권한·버전 불일치 | Connector 테스트, 권한 최소화 | playbook 실패율 |
| 책임 경계 불명확 | 탐지팀과 대응팀 역할 혼재 | RACI, 티켓 상태 정의 | SLA 위반 건수 |
| 비용 증가 | 로그 저장과 자동화 플랫폼 중복 투자 | 단계적 도입, 사용량 기반 관리 | EPS, Case당 비용 |

> 요약: SIEM-SOAR 연계 리스크는 경보 품질, API 연동, 조직 책임, 비용 구조를 분리해 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지 지표 | MTTD 10분 이하, 로그 커버리지 95% 이상 | SIEM 대시보드 |
| 대응 지표 | MTTR 30% 이상 단축 | SOAR Case 통계 |
| 자동화 품질 | playbook 성공률 95% 이상 | 실행 로그, 실패 분석 |
| 감사 증적 | 경보, 승인, 조치, 보고 100% 연결 | Case audit trail 샘플링 |

> 요약: 연계 성과는 MTTD, MTTR, playbook 성공률, 감사 증적 연결성으로 평가한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. SIEM 로그 커버리지와 correlation 룰을 먼저 정비하고, 고위험 경보에 자산 중요도와 사용자 맥락을 추가함.
2. 피싱, 악성 해시, 계정 탈취, WAF 반복 공격을 SOAR playbook 후보로 선정하고 승인·롤백 단계를 설계함.
3. SIEM MTTD와 SOAR MTTR을 분리 측정하고, 오탐 경보는 SIEM 룰로, 실패 조치는 SOAR playbook으로 개선함.

**결론 (2줄):**
- 기술사 판단: SIEM은 탐지 품질을, SOAR는 대응 속도와 절차 품질을 책임지므로 순차·연계 도입이 적절함.
- 향후 방향: 융합 관제는 SIEM, SOAR, XDR, UEBA를 통합해 탐지부터 대응까지 폐루프 운영으로 발전함.
