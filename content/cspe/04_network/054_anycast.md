## Ⅰ. 개요
- **정의**: 동일 IP 주소를 여러 노드에 할당하여 라우팅 프로토콜이 최근접 노드로 트래픽을 전달하는 기법임
- **배경/필요성**: 글로벌 서비스에서 사용자마다 다른 서버 IP를 안내하면 관리 복잡도가 증가하므로 단일 IP로 최적 경로를 자동 선택할 필요가 있음
- **비유**: 전국 동일 전화번호(예: 119)로 전화하면 가장 가까운 소방서가 응답하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Unicast/Multicast와의 차이, BGP 기반 동작 | BGP 경로 광고로 최근접 선택 | TCP 세션 유지 이슈 반드시 언급 |

> 요약: 동일 IP를 다수 노드가 공유하며 BGP 라우팅으로 최근접 노드가 응답하는 기법임

## Ⅱ. 구성요소
```text
         동일 IP: 1.2.3.4
           /     |     \
        Node A  Node B  Node C
        (서울)  (도쿄)  (미국)
          |       |       |
        BGP     BGP     BGP  --> 라우터가 최단 경로 선택
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Anycast IP | 다수 노드가 공유하는 단일 IP 주소 | 전국 공통 대표번호 |
| BGP 경로 광고 | 각 노드가 동일 IP 프리픽스를 자신의 AS에서 광고함 | 각 소방서가 관할 등록 |
| 라우팅 결정 | AS-Path·지연 등 메트릭 기반으로 최근접 노드를 선택함 | 가장 가까운 소방서 배정 |
| Failover | 노드 장애 시 BGP 철회로 트래픽이 차순위 노드로 자동 전환됨 | 관할 소방서 부재 시 인접 소방서 출동 |

> 요약: 동일 IP를 BGP로 광고하고 라우터가 최단 경로 노드를 선택하는 구조임

## Ⅲ. 절차
```text
IP 할당 --> BGP 광고 --> 라우팅 선택 --> 최근접 노드 응답
```
- 1단계: 복수 지역 노드에 동일 Anycast IP를 설정함
- 2단계: 각 노드가 BGP를 통해 동일 프리픽스를 자신의 AS에서 광고함
- 3단계: 인터넷 라우터가 AS-Path 길이·지연 기준으로 최적 경로를 선택함
- 4단계: 사용자 패킷이 최근접 노드로 도달하여 응답을 수신함

> 요약: IP 할당 → BGP 광고 → 라우팅 최적 경로 선택 → 최근접 노드 응답의 흐름임

## Ⅳ. 문제점
- TCP 세션 불안정: 라우팅 경로 변경 시 기존 TCP 연결이 다른 노드로 전환되어 세션이 끊김
- 트래픽 편중: BGP 메트릭이 실제 부하를 반영하지 못해 특정 노드에 트래픽이 집중됨
- 디버깅 난이도: 동일 IP가 여러 노드에 존재하므로 장애 노드 식별이 어려움

> 요약: TCP 세션 유지, 트래픽 편중, 장애 노드 식별이 주요 과제임

## Ⅴ. 개선방안
1. 단기: UDP 기반 서비스(DNS, NTP)에 우선 적용하여 TCP 세션 이슈를 회피함
2. 중기: BGP Community 속성과 트래픽 모니터링 연계로 부하 기반 경로 조정을 수행함
3. 장기: Segment Routing 결합으로 경로 세밀 제어 및 장애 구간 자동 우회를 구현함

> 요약: UDP 우선 적용, 부하 기반 경로 조정, SR 결합으로 단계별 개선이 가능함

## Ⅵ. 전망
- 발전 방향: CDN·DNS·DDoS 방어에서 표준 배포 방식으로 정착 중임(053 참조)
- 기술사적 판단: IPv6 확산과 함께 Anycast 활용 범위가 IoT 게이트웨이까지 확대됨
- 기술사 제언: Anycast 설계 시 노드 간 상태 동기화 전략과 Failover 시간 목표 수립이 필요함
