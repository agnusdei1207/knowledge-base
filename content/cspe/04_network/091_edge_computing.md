## Ⅰ. 개요
- **정의**: 데이터 발생 지점 근처에서 연산을 수행하여 지연을 줄이는 분산 컴퓨팅 모델
- **배경/필요성**: IoT 기기 폭증으로 중앙 클라우드까지 왕복 지연이 실시간 서비스 품질을 저해함
- **비유**: 본사(클라우드)에 보고하지 않고 현장 지사(엣지)에서 즉시 의사결정하는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 한계 극복 방안 이해 | 지연 감소·대역폭 절감 원리 | Fog Computing(092 참조)과 계층 차이 구분 |

> 요약: 데이터 원천 근처에서 처리하여 지연과 대역폭 부담을 줄이는 분산 아키텍처임

## Ⅱ. 구성요소
```text
[IoT Device] ---> [Edge Node] ---> [Cloud]
     |                |                |
  데이터 생성      로컬 처리       글로벌 집계
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Edge Node | 현장에 배치된 소형 서버로 데이터 필터링·추론 수행 | 현장 지사 담당자 |
| Edge Gateway | 다수 기기 데이터를 수집·프로토콜 변환하는 중간 장비 | 우체국 분류 센터 |
| Orchestrator | 엣지 노드 배포·스케일링·모니터링을 관리하는 제어 평면 | 본사 운영팀 |
| Cloud Backend | 장기 저장·모델 학습 등 대규모 연산 담당 | 본사 데이터센터 |

> 요약: 기기-엣지노드-게이트웨이-클라우드 계층으로 구성됨

## Ⅲ. 절차
```text
데이터 수집 --> 엣지 전처리 --> 로컬 판단 --> 클라우드 동기화
```
- 1단계: IoT 센서가 원시 데이터를 생성하여 엣지 노드로 전송함
- 2단계: 엣지 노드에서 필터링·정규화 등 전처리를 수행함
- 3단계: 추론 모델 또는 규칙 엔진으로 로컬 의사결정을 수행함
- 4단계: 집계 결과·이벤트 로그만 클라우드로 동기화함

> 요약: 수집-전처리-로컬판단-동기화 4단계로 지연을 최소화함

## Ⅳ. 문제점
- 보안 취약: 물리적으로 분산된 노드가 탈취·변조 공격에 노출됨
- 운영 복잡성: 수천 노드의 배포·패치·모니터링 부담이 큼
- 데이터 일관성: 엣지-클라우드 간 동기화 지연으로 상태 불일치 발생 가능

> 요약: 분산 배치에 따른 보안·운영·일관성 문제가 핵심임

## Ⅴ. 개선방안
1. 단기: 엣지 노드에 하드웨어 보안 모듈(TPM) 탑재로 무결성 검증
2. 중기: GitOps 기반 선언적 배포 파이프라인으로 운영 자동화
3. 장기: CRDT 등 최종 일관성 모델 적용으로 동기화 충돌 해소

> 요약: TPM 보안-자동 배포-일관성 모델 순으로 성숙도를 높여야 함

## Ⅵ. 전망
- 발전 방향: 5G MEC 표준과 결합하여 통신사 엣지 인프라로 확장
- 기술사적 판단: AI 추론 워크로드 증가로 엣지 GPU/NPU 수요 지속 확대 전망
- 기술사 제언: 엣지-클라우드 하이브리드 아키텍처 표준화와 보안 거버넌스 수립 필요
