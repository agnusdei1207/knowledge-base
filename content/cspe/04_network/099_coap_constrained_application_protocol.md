## 미리 알고가기

- 제한 장치는 메모리와 전력과 처리 능력이 작은 센서나 액추에이터를 뜻함
- REST는 자원을 URI로 식별하고 GET, POST, PUT, DELETE 같은 메서드로 다루는 방식임
- 확인형 메시지는 수신 확인이 필요한 메시지이고 비확인형 메시지는 빠르게 한 번 보내는 메시지임
- Observe는 자원 값이 바뀔 때마다 구독자에게 계속 알려 주는 CoAP 기능임

## Ⅰ. 개요

- **정의/개념**: CoAP은 작은 장치가 UDP 위에서 REST 방식으로 자원을 조회하고 변경할 수 있게 만든 경량 응용 프로토콜임
- **배경/필요성**: 소형 센서는 HTTP와 TCP 스택을 항상 유지하기 어렵기 때문에 더 작은 헤더와 단순한 절차로 자원 제어를 수행할 수 있는 방식이 필요함

## Ⅱ. 특징

- HTTP와 비슷한 자원 접근 모델을 유지하면서 메시지 형식을 훨씬 가볍게 가져감
- UDP 기반이라 단순하고 빠르지만 신뢰성은 프로토콜 내부 재전송으로 보완함
- Observe와 블록 전송 기능으로 상태 구독과 큰 데이터 전달을 지원함
- 보안과 재전송 설계를 소홀히 하면 UDP의 한계가 그대로 드러남

## Ⅲ. 종류 및 비교

| 판단 기준 | CoAP | HTTP |
|:---|:---|:---|
| 전송 기반 | UDP 기반으로 가볍게 동작함 | TCP 기반으로 연결 관리가 무거움 |
| 자원 접근 | REST 모델을 유지함 | REST 모델을 표준적으로 사용함 |
| 적합한 환경 | 소형 센서, 배터리 장치, 저대역폭 링크 | 일반 웹 서비스와 서버 연동 |
| 주의점 | 손실과 보안과 재전송 정책을 따로 챙겨야 함 | 오버헤드가 커서 제약 장치에 부담이 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 엔드포인트 | CoAP 요청과 응답을 주고받는 장치나 서버임 |
| 자원 URI | 센서 값이나 제어 대상처럼 접근할 객체를 식별함 |
| 메시지 타입 | 확인형과 비확인형으로 나뉘어 전송 특성을 조절함 |
| 토큰과 메시지 ID | 요청과 응답을 짝지어 중복과 재전송을 관리함 |
| 프록시와 보안 | HTTP 연동과 보안 통신 적용을 담당함 |

```text
+---------+    +---------+    +---------+    +---------+
| 장치 요청 | -> | CoAP 메시지 | -> | 서버 자원  | -> | 응답·통지    |
+---------+    +---------+    +---------+    +---------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자원 지정      | -> | 요청 전송      | -> | 확인·응답      | -> | 필요 시 재전송 | -> | 관찰 통지      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자원 지정**: 장치나 응용이 URI로 대상 자원을 정함
2. **요청 전송**: GET이나 PUT 같은 메서드로 메시지를 보냄
3. **확인과 응답**: 확인형이면 응답과 함께 수신 여부를 맞춤
4. **필요 시 재전송**: 손실이 감지되면 메시지 ID를 기준으로 다시 보냄
5. **관찰 통지**: 값이 바뀌는 자원은 Observe로 계속 알려 줄 수 있음

## Ⅵ. 실무 적용 및 유의점

1. 배터리 센서와 저대역폭 무선망에서는 CoAP이 잘 맞지만 패킷 손실이 잦으면 재전송이 오히려 혼잡을 키울 수 있으므로 확인형 사용 범위를 좁히고 응답 지연과 재전송률을 함께 봐야 함
2. 상위 시스템이 HTTP만 지원하는 경우에는 CoAP 프록시를 두되 자원 경로와 오류 코드 매핑이 엇갈리지 않게 관리하고 요청 성공률과 변환 지연을 확인해야 함

## Ⅶ. 결론

CoAP은 작은 장치에 HTTP를 억지로 올리는 대신 필요한 자원 접근 모델만 남겨 가볍게 구현한 프로토콜로 보면 이해가 쉬움
