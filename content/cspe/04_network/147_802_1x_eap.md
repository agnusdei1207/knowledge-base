# 📖 【암기용】 개념 완전 이해

> 목적: 802.1X와 EAP를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 네트워크 포트(랜선 구멍이나 와이파이 연결점) 자체에 자물쇠를 채워, 인증에 성공한 사람만 통과시키는 표준 기술
- **왜 필요한가**: 공용 장소의 랜선에 아무나 꽂으면 내부망이 뚫릴 수 있다. 802.1X는 "이 포트를 쓰려면 먼저 신분을 증명해"라고 요구하는 입구 보안의 핵심이다.
- **핵심 직관**: 아파트 현관문(네트워크 포트)에 카드키(인증서/ID)를 대야 문이 열리는 시스템과 같다. 인증되지 않으면 랜선을 꽂아도 데이터가 하나도 안 통한다.

## 깊이 이해
- **배경·문제의식**: 과거에는 IP 주소만 알면 네트워크를 쓸 수 있었다. 하지만 이제는 기기 자체가 아닌 '사람'의 신원을 포트 단위에서 검증해야 할 필요가 생겼다.
- **작동 원리**: 세 가지 주인공이 필요하다.
  - **Supplicant (신청자)**: 접속하려는 노트북이나 스마트폰.
  - **Authenticator (인증자)**: 스위치나 무선 공유기(AP). 문지기 역할만 하고 직접 판단은 안 한다.
  - **Authentication Server (인증 서버)**: 보통 RADIUS 서버. 실제 ID/비밀번호가 맞는지 판단하는 대법관 역할.
- **EAP (Extensible Authentication Protocol)**: 실제 어떤 방식으로 인증할지(비밀번호, 인증서, OTP 등)를 유연하게 바꿀 수 있게 해주는 '대화 약속'이다.
- **비유**: 보안 검색대(Authenticator)에 여권(EAP 패킷)을 내밀면, 직원이 본국 시스템(Auth Server)에 조회해 보고 통과시켜 주는 과정과 같다.
- **구체 예시**: 대학이나 회사 와이파이 연결 시 ID와 비밀번호를 입력하라는 창이 뜨는 방식이 주로 EAP-PEAP 방식의 802.1X 인증이다.
- **흔한 오해·주의점**: "와이파이 비밀번호(PSK)와 뭐가 다른가?" PSK는 모두가 같은 암호를 공유하므로 한 명만 유출돼도 다 뚫리지만, 802.1X는 개인별 ID나 인증서를 쓰므로 훨씬 안전하다.

## 연결 개념
- **RADIUS (Remote Authentication Dial-In User Service)**: 802.1X에서 가장 많이 쓰이는 인증 서버 프로토콜
- **NAC**: 802.1X를 활용하여 기기의 보안 상태까지 체크하는 상위 시스템
- **MAB (MAC Authentication Bypass)**: 프린터처럼 802.1X를 못 하는 기기를 MAC 주소로 통과시키는 예외 처리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 802.1X의 3가지 구성요소(Supplicant, Authenticator, AS)와 EAP의 다양한 인증 방식(TLS, TTLS, PEAP)의 차이점을 보안성과 복잡도 측면에서 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 802.1X는 포트 기반 네트워크 접근 제어(PNAC) 표준으로, 단말-인증자-서버 간의 EAP 프로토콜 교환을 통해 네트워크 접속 권한을 부여한다.
> 2. **가치**: 포트 단위의 개별 사용자 인증과 동적 VLAN 할당을 지원하여, 내부망 침입 방지 및 사용자 기반 보안 정책 적용을 가능케 한다.
> 3. **판단 포인트**: 구축 환경에 따라 인증서 기반의 강력한 보안(EAP-TLS)과 ID/PW 기반의 편의성(EAP-PEAP) 중 적절한 메커니즘을 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 포트 보안 및 사용자 인증 체계 이해 확인 | 3개 구성요소(S/A/AS), EAPOL 프로토콜 | 구성요소 간 데이터 흐름(EAP encapsulated in RADIUS 등) 누락 |
| EAP 인증 방식별 보안 특성 비교 역량 | EAP-TLS(양방향), EAP-PEAP(단방향 TLS), EAP-TTLS | 방식별 인증서 필요 위치(Client/Server) 혼동 |
| RADIUS 및 계층별 보안 프로토콜 파악 | 802.1X-RADIUS 연동, UDP 1812/1813 포트 | 프로토콜 계층도(Layering) 없이 글자로만 나열 |

> 요약: 802.1X 프레임워크 내에서 EAP가 어떻게 캡슐화되어 전달되는지 그 메커니즘을 부각함.

## Ⅰ. 개요 및 필요성

- 정의: LAN 접속 단말에 대해 포트 단위로 신원을 확인하여 네트워크 접근을 통제하는 IEEE 802.1X 표준 기술
- 배경: 물리적인 포트 노출에 따른 불법 침입 위험, 공용 Wi-Fi의 공유 비밀번호(PSK) 보안 한계 극복 필요
- 필요성: 개인별 ID/인증서 기반 책임 추적성 확보, 중앙 집중형 인증 관리(AAA), 비인가 기기 접속 차단

---

## Ⅱ. 구조 및 구성요소

```text
[802.1X 인증 아키텍처]
Supplicant (PC/Phone) <--- [EAPOL] ---> Authenticator (Switch/AP) <--- [RADIUS/EAP] ---> Authentication Server
(인증 요청자)                          (중계 및 제어자)                               (판단 및 처리자)
```

| 구성요소 | 역할 및 특징 | 주요 기술 |
|:---|:---|:---|
| Supplicant | 인증을 요청하는 단말의 소프트웨어/드라이버 | EAP Client, OS Native |
| Authenticator | 단말과 서버 사이에서 메시지 중계 및 포트 개방 제어 | L2 스위치, AP, WLC |
| Auth Server (AS) | 사용자 정보를 검증하고 승인/거부 결과 통보 | RADIUS, Diameter |
| EAPOL | Ethernet 상에서 EAP 패킷을 전송하기 위한 캡슐화 | IEEE 802.1X-2004/2010 |

> 요약: 단말은 스위치와 EAPOL로 소통하고, 스위치는 서버와 RADIUS(EAP 포함)로 소통하여 인증을 완결함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[802.1X 인증 시퀀스]
1. Link Up -> 2. EAP-Request/Identity -> 3. EAP-Response (ID) -> 4. RADIUS Access-Request
                                                                        |
7. Port Open <- 6. EAP-Success <--------- 5. RADIUS Access-Accept <-----+
```

| 단계 | 처리 내용 | 프로토콜 전환 |
|:---:|:---|:---|
| 1 | 단말이 포트에 연결되거나 인증 요청(EAPOL-Start) 송신 | EAPOL (Layer 2) |
| 2 | 인증자(스위치)가 단말의 ID 정보를 요청 | EAP-Request/Identity |
| 3 | 인증자가 수신한 EAP 패킷을 RADIUS 패킷에 담아 서버로 전달 | EAP over RADIUS (UDP) |
| 4 | 서버가 데이터베이스 확인 후 성공(Accept) 또는 거부(Reject) 응답 | RADIUS Access-Accept |
| 5 | 성공 시 스위치가 해당 포트의 차단을 해제하여 데이터 통신 허용 | Auth Success (Port Open) |

> 요약: 인증 성공 전에는 오직 인증 관련 패킷(EAPOL)만 통과시키고, 성공 후에만 일반 데이터를 허용함.

## Ⅳ. 특징

| 구분 | EAP-TLS | EAP-PEAP | EAP-TTLS |
|:---|:---|:---|:---|
| 인증 수단 | 디지털 인증서 | ID / Password | ID / Password |
| 보안성 | 최고 (양방향 인증) | 높음 (서버 인증 + 터널) | 높음 (서버 인증 + 터널) |
| 클라이언트 인증서 | **필수** | 불필요 | 불필요 |
| 구축 난이도 | 높음 (인증서 배포 필요) | 보통 (AD 연동) | 보통 |
| 판단 포인트 | 최고 보안 요구 환경 | 일반 기업용 환경 | 유연한 내부 인증 방식 |

> 요약: 보안성을 중시하면 EAP-TLS를, 배포 편의성을 중시하면 EAP-PEAP를 선택함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | PSK (Pre-Shared Key) | 802.1X (Enterprise) | 선택 기준 |
|:---|:---|:---|:---|
| 비밀번호 공유 | 모든 사용자 동일 암호 | 사용자별 고유 계정/인증서 | 보안 책임성 |
| 키 갱신 | 한 명 유출 시 전체 변경 | 개인별 계정만 삭제/변경 | 운영 유지보수 |
| 인프라 요구 | AP만 있으면 가능 | RADIUS 서버 필요 | 예산 및 인프라 |

> 요약: 소규모 가정용은 PSK가 유리하나, 기업 환경에서는 중앙 통제가 가능한 802.1X가 필수임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 인증 서버 장애 | RADIUS 서버 단일 지점 장애(SPOF) | 서버 이중화 및 Critical VLAN 설정 | 인증 지연 시간 < 500ms |
| 단말 호환성 | 802.1X 미지원 단말(IP카메라 등) | MAB (MAC 인증) 적용 | MAB 단말 리스트 관리 |
| 중간자 공격 (MitM) | 위조된 인증자(Rogue AP) 접속 | 서버 인증서 기반 검증 필히 적용 | 비인가 AP 탐지 건수 |

> 요약: 가용성을 위한 서버 이중화와 미지원 기기를 위한 MAB(MAC 인증) 보완책이 반드시 동반되어야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 성공률 | 99% 이상 | RADIUS 서버 Accept/Reject 로그 |
| 포트 차단 유효성 | 비인가 단말 접속 시 100% 차단 | 모의 침투 및 포트 스캔 |
| 사용자 가시성 | 접속 IP-ID-MAC 매칭 정보 확보 | IP 관리 시스템(IPMS) 연동 |

> 요약: 인증 데이터의 무결성과 비인가 접속 차단율을 통해 시스템 유효성을 정기 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **동적 VLAN 할당 (Dynamic VLAN)**: 인증 성공 시 사용자의 부서 정보에 따라 영업팀 VLAN(10), 개발팀 VLAN(20)을 포트에 자동 할당
2. **AD 연동 SSO 구현**: 윈도우 로그인 계정을 802.1X 인증에 그대로 사용하여 사용자 편의성을 높이고 중복 인증 제거
3. **무선 구간 WPA3-Enterprise 적용**: 최신 Wi-Fi 6/7 환경에서 802.1X(EAP-TLS)를 결합하여 공중 구간 데이터 암호화 강화

**결론 (2줄):**
- 기술사 판단: 802.1X는 네트워크 진입 단계의 가장 강력한 표준 관문이며, ZTNA(Zero Trust Network Access)의 기초 구성 요소임
- 향후 방향: 단순 ID/PW를 넘어 단말의 상태(Compliance) 정보까지 연동하는 차세대 NAC 아키텍처로 확장될 것임
