## 미리 알고가기

- HTTP는 웹 브라우저와 웹 서버가 데이터를 주고받는 응용 계층 프로토콜임
- SQL 삽입은 입력값에 데이터베이스 명령을 끼워 넣는 공격임
- 크로스 사이트 스크립팅은 악성 스크립트를 웹 페이지에 심는 공격임
- 가상 패치는 애플리케이션 코드를 고치기 전 우회 규칙으로 먼저 막는 방식임

## Ⅰ. 개요

- **정의/개념**: WAF는 HTTP 요청과 응답을 해석해 웹 애플리케이션을 노리는 공격 패턴과 비정상 입력을 차단하는 응용 계층 보안 통제 장치임
- **배경/필요성**: 네트워크 방화벽은 포트와 주소는 잘 보지만 URL과 파라미터와 쿠키 의미까지는 이해하지 못하므로, 웹 입력을 직접 검사할 별도 방어 계층이 필요함

## Ⅱ. 특징

- 웹 요청 본문과 헤더와 파라미터를 이해하므로 웹 공격 대응에 특화됨
- 차단뿐 아니라 가상 패치와 봇 제어와 접속 속도 제한에도 활용됨
- 애플리케이션 특성에 맞게 규칙을 다듬지 않으면 오탐이 늘 수 있음
- 보안 코딩을 대체하지는 못하고 노출 시간을 줄이는 역할에 가깝음

## Ⅲ. 종류 및 비교

| 판단 기준 | 네트워크 방화벽 | WAF |
|:---|:---|:---|
| 보는 정보 | IP와 포트와 세션 중심임 | URL과 파라미터와 쿠키까지 해석함 |
| 주된 공격 | 네트워크 차단과 세션 제어에 강함 | 웹 입력 기반 공격 차단에 강함 |
| 정책 단위 | 주소와 포트 정책이 중심임 | 웹 요청 규칙과 애플리케이션 맥락이 중심임 |
| 대표 위치 | 네트워크 경계에 배치함 | 웹 서버 앞단이나 프록시 구간에 둠 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 클라이언트 | 웹 요청을 보내는 주체임 |
| WAF 엔진 | 요청을 정규화하고 규칙에 따라 검사함 |
| 정책·시그니처 | 허용 기준과 차단 패턴을 정의함 |
| 웹 서버 | 실제 애플리케이션을 제공함 |
| 로그·학습 기능 | 차단 결과와 오탐 사례를 모아 정책을 다듬음 |

```text
+-----------+    HTTP 요청    +----------+    허용된 요청    +---------+
| 클라이언트  | ------------> | WAF 엔진   | --------------> | 웹 서버   |
+-----------+               +----------+                  +---------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
[요청 수신] -> [정규화] -> [규칙 검사] -> [허용·차단] -> [로그 기록]
```

1. **요청 수신**: 브라우저나 API 클라이언트 요청을 받음
2. **정규화**: 인코딩과 우회 문자열을 풀어 원형을 맞춤
3. **규칙 검사**: 시그니처와 허용 정책과 이상 행위를 점검함
4. **허용·차단**: 정상 요청만 웹 서버로 전달함
5. **로그 기록**: 차단과 예외 사례를 저장해 튜닝에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 외부 노출 웹 서비스는 코드 수정 전에 WAF로 위험 요청을 줄일 수 있지만 서비스별 정상 입력 패턴을 모르면 오탐이 늘어나므로 학습 모드와 규칙 튜닝을 함께 거치고 차단 정확도와 우회 시도와 정상 요청 오탐 건수를 같이 확인함
2. 취약한 레거시 웹 시스템은 가상 패치가 특히 유용하지만 애플리케이션 수정이 늦어지면 규칙 의존이 커지므로 코드 보완 일정과 예외 규칙 관리를 함께 운영하고 미해결 취약점 수와 긴급 차단 규칙 누적을 계속 봐야 함

## Ⅶ. 결론

WAF의 핵심은 웹 요청의 의미를 이해해 애플리케이션 바로 앞에서 막아 주는 데 있으며, 효과는 규칙 품질과 애플리케이션 이해 수준에 달려 있음.
