# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: ISO/IEC 27001은 조직의 정보 자산 위험을 평가하고, 그 결과에 따라 **Annex A 통제**를 선택·운영하는 **정보 보안 경영 시스템(ISMS) 국제 표준**이다.
- **왜 필요한가**: 보안 사고는 기술 통제(방화벽·암호화) 하나만으로 막을 수 없다. 조직의 정책·책임·자원 배분·지속 개선 체계가 없으면 통제가 도입돼도 유지되지 않는다.
- **핵심 직관**: 건강검진 후 위험 부위를 찾아 맞춤 처방을 정하고, 매년 재검진으로 처방을 갱신하는 구조다 — '위험 평가 → 통제 선택 → 심사 → 개선'의 PDCA 반복이 핵심이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| ISO 27001 (상위 키워드) | 정보 보안 경영 시스템(ISMS) 인증 표준 | 건강검진 + 맞춤 처방 + 재검진 체계 |
| ISMS (Information Security Management System) | 정보 보안을 관리하는 경영 시스템 | 건강 관리 체계 |
| 위험 평가 (Risk Assessment) | 정보 자산별 위협·취약점·영향도를 산정 | 건강검진 |
| Annex A 통제 | 조직적·인적·물리적·기술적 통제군(4범주, 93개 통제) | 처방 목록 |
| SoA (Statement of Applicability) | 통제 적용·제외 근거를 문서화한 적용성명서 | 처방전(이 약은 처방, 이 약은 제외한 이유) |
| PDCA (Plan-Do-Check-Act) | 정책 수립 → 실행 → 점검 → 개선의 반복 | 처방 → 복용 → 재검진 → 처방 갱신 |
| 내부심사 (Internal Audit) | 조직 자체 통제 운영 점검 | 자가 건강 체크 |
| 경영검토 (Management Review) | 경영진이 보안 정책·자원·위험을 검토 | 의사와 환자의 정기 상담 |
| 사후관리심사 (Surveillance Audit) | 인증 후 매년 외부 기관이 운영 증거를 확인 | 매년 재검진 |
| ISO 27002 | Annex A 통제 구현 상세 가이드(인증 대상 아님) | 처방 약품 상세 설명서 |

## 깊이 이해
- **배경·문제의식**: 단일 기술 도입(방화벽·암호화)만으로는 조직 전체 위험을 커버하지 못한다. 부서마다 다른 기준으로 보안을 판단하면 책임 소재와 예산 우선순위가 흔들린다. ISO 27001은 위험 평가 결과를 근거로 통제를 선택하게 해 경영진 의사결정과 보안 활동을 연결한다.
- **작동 원리**:
  - ① 조직은 ISMS 적용 범위(Scope)를 정의하고 정보 자산을 식별한다.
  - ② 각 자산에 대해 기밀성·무결성·가용성 관점에서 위험을 평가한다(위협·취약점·영향도 산정).
  - ③ 위험 평가 결과에 따라 Annex A 통제군(조직적·인적·물리적·기술적, 93개)에서 필요한 통제를 선택한다.
  - ④ 선택 근거와 제외 사유를 SoA에 문서화한다 — 인증심사에서 SoA가 핵심 확인 문서다.
  - ⑤ PDCA(Plan-Do-Check-Act) 방식으로 정책 수립, 통제 실행, 내부심사·경영검토, 개선을 반복한다.
  - ⑥ 인증 기관이 최초 인증심사 후 매년 사후관리심사(surveillance audit)로 통제 운영 증거를 확인하고, 3년 주기로 갱신심사를 수행한다.
- **비유**: 보안팀이 전 재산을 다 지키는 게 아니라, 도둑이 노릴 만한 금고와 문부터 우선순위를 매겨 잠그는 방식이다. 잠그는 이유와 잠그지 않는 이유를 처방전(SoA)에 남기고, 매년 도둑 동향(위협)을 확인해 처방을 갱신한다.
- **구체 예시**: 위험 평가에서 고객 DB 서버의 무단 접근 위험이 높다고 판단되면, 접근 통제·로그 모니터링·암호화 통제를 SoA에 적용 대상으로 명시한다. 반면 공개 웹사이트는 기밀성 위험이 낮아 암호화 통제를 제외하고 그 사유를 SoA에 기록한다.
- **흔한 오해·주의점**: ① ISO 27001 인증이 있다고 해서 모든 보안 사고가 방지되는 것은 아니다 — 인증은 '체계를 갖추고 운영하고 있다'는 증거이지 '사고가 없다'는 보증이 아니다. ② Annex A 통제를 93개 전부 적용해야 하는 것이 아니라, 위험 평가 결과에 따라 선택하고 제외 사유를 SoA에 남기면 된다. ③ 한국의 ISMS-P 인증과 별도 제도다 — 국제 표준(ISO) vs 한국 법정 인증(ISMS-P)이며, 심사 항목·인증 기관이 다르다.

## 연결 개념
- **ISO 27002**: 27001 Annex A 통제의 구현 상세 가이드 — 27001이 '무엇을', 27002가 '어떻게'를 담당
- **ISO 27701**: 27001 위에 개인정보 관리 요구사항을 얹은 확장 표준
- **ISMS-P (한국)**: 한국 정보보호·개인정보 관리체계 인증 — ISO 27001과 별도 제도이나 통제 항목 상당 부분 중첩
- **PDCA·위험관리**: 경영 시스템의 기본 운영 방식

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO 27001은 위험 평가 결과에 따라 Annex A 통제를 선택·운영하는 정보 보안 경영 시스템 국제 표준임.
> 2. **가치**: 통제 선택 근거를 SoA로 문서화해 경영진 의사결정과 보안 활동의 정합성을 확보함.
> 3. **판단 포인트**: 인증 취득이 아닌 PDCA 반복을 통한 통제 유지와 사후관리심사 통과로 실효성을 판단함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ISMS 구조 이해 | 위험 평가 → Annex A 통제 선택 → SoA 문서화 | 통제 목록만 나열, 위험 평가 근거 누락 |
| 인증 절차 이해 | 내부심사 → 경영검토 → 최초심사 → 사후관리심사 | 인증을 1회성 이벤트로 서술 |
| PDCA 운영 | Plan-Do-Check-Act 반복, 지속 개선 | Plan만 설명하고 Check-Act 생략 |

> 요약: 통제 목록 나열이 아닌, 위험 평가 → SoA → PDCA → 심사로 이어지는 근거 체계를 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 위험 평가 기반으로 Annex A 통제를 선택·운영하는 정보 보안 경영 시스템(ISMS) 국제 표준임
- 배경: 단일 기술 통제만으로는 조직 전체 보안을 유지할 수 없어 경영 체계 표준이 요구됨
- 필요성: 위험 평가 근거의 통제 선택, SoA 문서화, PDCA 반복, 사후관리심사 대응 체계 구축이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
적용 범위(Scope) 정의 -> 정보 자산 식별 -> 위험 평가
  -> Annex A 통제 선택 -> SoA 문서화
  -> 내부심사 -> 경영검토 -> 인증심사(최초/사후관리/갱신)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 적용 범위(Scope) | ISMS가 다루는 조직·자산·위치 정의 | 범위 밖 자산은 통제 대상 제외 |
| 위험 평가 | 자산별 위협·취약점·영향도 산정 | 자산 목록·위험 수용 기준 필요 |
| Annex A 통제 | 조직적·인적·물리적·기술적 4범주 93개 통제 | 위험 평가 결과에 따라 선택 |
| SoA | 통제 적용·제외 근거 문서 | 인증심사 핵심 확인 문서 |
| 인증 기관 | 최초·사후관리·갱신 심사 수행 | 공인 인정기구(AB) 산하 |

> 요약: Scope → 위험 평가 → 통제 선택 → SoA → 심사로 이어지는 문서 기반 체계임.

---

## Ⅲ. 동작원리 및 흐름도

```text
Plan: 자산 식별 -> 위험 평가 -> 통제 선택 -> SoA 문서화
Do: 통제 실행·운영
Check: 내부심사 -> 경영검토
Act: 개선 조치 -> 차기 PDCA 반복
외부: 인증심사(최초) -> 사후관리심사(매년) -> 갱신심사(3년)
```

1. Plan — 위험 평가·SoA: 정보 자산을 식별하고 기밀성·무결성·가용성 위험을 평가해 Annex A 통제를 선택하며 SoA에 근거를 문서화함
2. Do — 통제 실행: 선택된 통제를 실행·운영하고 운영 증거(로그·기록)를 확보함
3. Check — 내부심사·경영검토: 연 1회 이상 내부심사로 통제 운영 증거를 점검하고, 경영검토에서 정책·자원·위험을 재검토함
4. Act — 개선·심사: 부적합 사항을 시정하고 개선 조치를 실행하며, 외부 인증 기관의 사후관리심사(매년)·갱신심사(3년)를 통과함

> 요약: PDCA 반복(Plan-Do-Check-Act)과 외부 심사(사후관리·갱신)로 통제를 지속 유지함.

---

## Ⅳ. 특징
- 위험 기반 통제 선택: 모든 통제를 적용하는 것이 아닌, 위험 평가 결과에 따라 선택·제외하고 SoA에 근거를 남김
- PDCA 반복 체계: 1회성 인증이 아닌 Plan-Do-Check-Act 반복으로 통제를 지속 유지·개선함
- 외부 검증: 공인 인증기관의 최초·사후관리·갱신 심사로 운영 증거를 외부에서 검증함
- 경영 연계: 경영검토에 예산·자원·정책 결정을 포함해 경영진 의사결정과 보안 활동을 연결함

> 요약: 위험 기반 선택·PDCA 반복·외부 검증·경영 연계가 ISO 27001의 4대 특징임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | ISO 27002 (통제 가이드) | ISO 27001 (경영 시스템) | 선택 기준 |
|:---|:---|:---|:---|
| 성격 | 통제 항목별 구현 가이드 | 인증 가능한 경영 시스템 요구사항 | 인증 목적이면 27001, 구현 참고는 27002 |
| 인증 여부 | 인증 대상 아님 | 인증 대상 표준 | 대외 신뢰 증빙 필요 시 27001 |
| 활용 관계 | 27001 Annex A 통제의 구현 상세 | 27002를 참고해 통제 수준 결정 | 두 표준 병행 적용 |

> 요약: 27002는 통제 구현 상세를, 27001은 경영 시스템 인증 요구사항을 제공하며 병행 적용함.

**리스크·대응:**
- SoA-실제 불일치: SoA 문서와 실제 운영 통제가 불일치 → 내부심사에서 운영 증거 표본 점검 (지표: 부적합 사항 재발률)
- 위험 평가 형해화: 매년 동일 위험 목록 반복 → 위협 인텔리전스·사고 이력 반영한 재평가 (지표: 위험 평가 갱신 이력)
- 경영진 무관심: 경영검토가 형식적으로 진행 → 경영검토에 예산·자원 결정 항목 포함 (지표: 경영검토 실행 항목 이행률)

**점검 지표:**
- 통제 이행: SoA 적용 통제 100% 운영 증거 확보 — 내부심사 표본 점검
- 심사 통과: 매년 사후관리심사 무중대 부적합 통과 — 인증기관 심사 보고서

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 위험 평가·SoA 갱신: 정보 자산 목록과 위험 평가를 연 1회 이상 재평가하고, 위협 인텔리전스·사고 이력을 반영해 SoA를 갱신함
2. 내부심사·경영검토 실질화: 내부심사에서 운영 증거 표본을 점검하고, 경영검토에 예산·자원 결정 항목을 포함해 형식화를 방지함
3. 사후관리심사 사전 대비: 부적합 시정조치를 90일 이내 완료하고, 사후관리심사 전 이행 증거를 정리함

**결론:**
- 기술사 판단: ISO 27001은 통제 목록이 아닌 위험 평가-통제 선택-PDCA 반복-심사로 이어지는 경영 체계로 접근해야 함
- 향후 방향: 개인정보(27701)·AI 거버넌스(42001)·사업연속성(22301) 등 인접 경영 시스템과 통합 심사(IMS)를 검토해야 함
