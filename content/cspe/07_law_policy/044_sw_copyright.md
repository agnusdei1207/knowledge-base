# 📖 【암기용】 개념 완전 이해

> 목적: SW 저작권을 처음 봐도 코드의 무엇이 보호되고 무엇이 보호되지 않는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 소스코드·오브젝트코드를 어문저작물에 준하는 저작물로 보호하는 저작권 제도
- **왜 필요한가**: 개발에 투입한 시간·비용을 회수하려면 무단 복제·배포를 막을 배타적 권리가 필요함
- **핵심 직관**: 요리 레시피의 아이디어(조리법 자체)는 보호받지 못하지만, 레시피를 적은 구체적인 글(코드)은 보호받는 것과 같음

## 깊이 이해
- **배경·문제의식**: 소프트웨어는 창작과 동시에 코드가 생성되지만 복제 비용이 거의 0에 가까워 무단 복제 유인이 큼
- **작동 원리**: 저작권은 코드의 구체적 표현(문장·구조·주석)을 보호하고, 알고리즘·기능·아이디어 자체는 보호 대상에서 제외됨(아이디어-표현 이분법)
- **작동 원리**: 창작과 동시에 저작권이 자동 발생하며, 등록은 분쟁 시 입증을 쉽게 하는 임의 절차임
- **작동 원리**: 저작인격권(공표권·성명표시권·동일성유지권)은 양도 불가하고, 저작재산권(복제·배포·전송권)은 양도·라이선스 가능함
- **작동 원리**: 직무상 작성한 프로그램은 계약이나 별도 정함이 없으면 법인 등 사용자가 저작자가 되는 업무상저작물 규정이 적용됨
- **비유**: 저작인격권은 부모와 자식 관계처럼 양도할 수 없는 관계이고, 저작재산권은 부동산처럼 사고팔 수 있는 재산이다
- **구체 예시**: 동일한 정렬 알고리즘을 다른 변수명·구조로 독립적으로 구현하면 저작권 침해가 아니지만, 소스코드를 그대로 복사해 사명만 바꾸면 침해가 성립함
- **흔한 오해·주의점**: 리버스 엔지니어링은 상호운용성 확보 목적 등 제한적으로 허용되는 예외가 있으며, 저작권 침해가 항상 성립하는 것은 아님

## 연결 개념
- 지식재산권 — 저작권이 속한 상위 권리 체계
- 오픈소스 라이선스 — 저작권을 기반으로 이용조건을 정하는 계약
- 오픈소스 컴플라이언스·SBOM — 저작권 준수를 실무에서 관리하는 절차

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SW 저작권 답안은 아이디어-표현 이분법, 저작인격권·저작재산권 구분, 업무상저작물 규정, 침해 방지 실무를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SW 저작권은 코드의 구체적 표현을 창작과 동시에 자동 보호하는 권리이다.
> 2. **가치**: 알고리즘 아이디어가 아닌 표현을 보호해 독립 개발과 혁신 경쟁을 동시에 허용한다.
> 3. **판단 포인트**: 저작인격권은 양도 불가, 저작재산권은 양도·라이선스 가능하다는 구분이 실무 계약의 핵심 기준이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보호 범위 이해 확인 | 아이디어-표현 이분법, 알고리즘 비보호 | "코드 전체가 보호된다"는 과잉 일반화 |
| 권리 구조 이해 확인 | 저작인격권(양도불가) vs 저작재산권(양도가능) | 두 권리를 구분 없이 서술 |
| 실무 계약 판단 확인 | 업무상저작물, 라이선스, 침해 방지 절차 | 침해 판단 기준 없이 결론만 서술 |

> 요약: 이 문제는 코드가 저작물이라는 사실보다 아이디어-표현 이분법과 두 권리의 양도 가능 여부 구분이 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: 소스코드·오브젝트코드의 구체적 표현을 저작물로 보호하는 제도
- 배경: 창작과 동시에 자동 발생, 등록은 분쟁 대비 임의 절차
- 필요성: 알고리즘 아이디어는 공유하되 구체적 구현 표현은 보호해 개발 투자와 혁신 경쟁의 균형이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
코드 창작 -> 아이디어/표현 분리
  -> 아이디어(알고리즘, 기능): 비보호
  -> 표현(소스코드, 구조, 주석): 저작권 자동 발생
  -> 저작인격권(공표/성명표시/동일성유지)
  -> 저작재산권(복제/배포/전송) -> 라이선스·양도
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 아이디어-표현 이분법 | 보호 대상과 비보호 대상 구분 | 알고리즘·인터페이스 규격은 비보호 |
| 저작인격권 | 공표권·성명표시권·동일성유지권 보호 | 양도 불가, 저작자 전속 |
| 저작재산권 | 복제·배포·전송·2차적저작물작성권 보호 | 양도·라이선스 가능 |
| 업무상저작물 | 직무상 창작물의 저작자 귀속 규정 | 별도 계약 없으면 법인이 저작자 |

> 요약: 표현만 저작권으로 보호되며, 인격권은 전속되고 재산권은 계약으로 이전 가능하다.

---

## Ⅲ. 동작원리 및 흐름도

```text
코드 작성 -> 창작성 판단(표현의 구체성)
  -> 저작권 자동 발생
  -> 침해 의심 발생 시 표현 유사성 비교
  -> 업무상저작물/계약 관계 확인 -> 권리 귀속 판단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 코드가 창작적 표현인지 판단 | 독자적 표현 존재 여부 |
| 2 | 저작권 자동 발생, 등록 여부 결정 | 등록 시 입증 편의성 |
| 3 | 침해 의심 시 소스코드 유사성 비교 | 구조·순서·조직 유사도 |
| 4 | 업무상저작물·계약 조건에 따라 권리자 확정 | 근로계약, 도급계약 조항 |

> 요약: 창작성 판단 후 자동 보호가 발생하고, 분쟁 시 표현 유사성과 계약관계로 권리 귀속을 판단한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 등록 없이 창작 즉시 보호되어 초기 비용 부담이 적음 | 스타트업 신속 개발에 유리 |
| 한계 | 알고리즘 자체는 보호되지 않아 독립 구현으로 회피 가능 | 핵심 로직 보호는 특허·영업비밀 병행 필요 |
| 비교 포인트 | 저작인격권은 양도 불가, 저작재산권은 양도 가능 | 계약서에 재산권 양도 범위 명시 필요 |

> 요약: SW 저작권은 신속한 자동 보호를 제공하지만 알고리즘 보호에는 한계가 있어 특허·영업비밀과 병행해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 저작권 | 특허 | 영업비밀 | 선택 기준 |
|:---|:---|:---|:---|:---|
| 보호 대상 | 코드 표현 | 알고리즘 발명 | 비공개 로직·데이터 | 표현 도용 방지는 저작권으로 충분 |
| 발생 요건 | 창작과 동시 자동 | 출원·심사 필요 | 비밀관리 필요 | 핵심 알고리즘은 특허·영업비밀 병행 |
| 회피 가능성 | 독립 구현 시 회피 가능 | 청구항 범위 내 회피 어려움 | 역설계로 유출 가능 | 회피 위험 높은 로직은 다중 보호 적용 |

> 요약: 코드 표현 보호는 저작권, 핵심 알고리즘 보호는 특허·영업비밀을 병행해 다층 방어 체계를 구성한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 소스코드 무단 복제 | 배포본 역컴파일, 코드 유출 | 난독화, DRM, 라이선스 감사 | 라이선스 위반 탐지 건수 |
| 권리 귀속 분쟁 | 외주 개발 계약에 재산권 이전 조항 누락 | 도급계약서 권리 귀속 조항 명시 | 계약 검토 완료율 |
| 저작인격권 침해 | 코드 수정 후 원저작자 성명표시 누락 | 라이선스 고지 자동화, 코드 헤더 관리 | 고지 누락 건수 |

> 요약: SW 저작권 리스크는 코드 보호 기술, 계약서 권리귀속 명시, 저작자 표시 관리로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 권리 관리 | 외주 개발 계약의 재산권 이전 조항 포함율 100% | 계약서 검토 대장 |
| 침해 방지 | 코드 유사성 검사 도구 적용률 | 코드 스캔 결과 |
| 라이선스 준수 | 서드파티 코드 출처·라이선스 명시율 | SBOM·라이선스 점검표 |

> 요약: 도입 후 성공 여부는 계약서 권리귀속 명시율, 코드 유사성 검사 적용률, 라이선스 명시율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단기: 외주·직무 개발 계약서에 저작재산권 귀속과 이전 범위를 명시함
2. 중기: 코드 유사성 검사와 라이선스 스캔 도구를 CI/CD에 통합해 침해·위반을 조기 탐지함
3. 장기: 핵심 알고리즘은 저작권과 별도로 특허·영업비밀 보호 전략을 병행 수립함

**결론 (2줄):**
- 기술사 판단: 코드 표현 보호는 저작권 자동 발생에 의존하되 핵심 로직은 특허·영업비밀로 이중 보호함
- 향후 방향: AI 코드 생성 확산에 따라 생성 코드의 저작권 귀속·침해 판단 기준이 새롭게 정립되어야 함
