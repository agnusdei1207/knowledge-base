# 📖 【암기용】 개념 완전 이해

> 목적: ISO/PAS 8800을 처음 봐도 기존 자동차 안전표준과 무엇이 다른지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.
> 주의: ISO/PAS 8800은 비교적 최근(2024년경) 공표된 PAS(Publicly Available Specification, 공개 표준 초안 성격의 문서)로, 정식 ISO 표준으로 전환되는 과정에 있어 세부 조항은 확정 국제표준 대비 변경 가능성이 있다.

## 한눈에
- **개요**: 자율주행차의 AI·머신러닝 구성요소에 특화된 안전 요구사항을 다루는 ISO PAS(공개표준초안) 문서
- **왜 필요한가**: 기존 ISO 26262(기능안전), ISO 21448(SOTIF)는 결정론적 소프트웨어를 전제로 설계되어, 데이터 기반으로 학습하고 확률적으로 판단하는 AI 컴포넌트의 고유 위험을 다루지 못함
- **핵심 직관**: ISO 26262가 "부품이 고장 나지 않게" 만드는 표준이고 ISO 21448이 "고장 안 나도 오판하지 않게" 만드는 표준이라면, ISO/PAS 8800은 "학습된 AI가 처음 보는 상황에서도 안전하게 판단하게" 만드는 표준이다

## 깊이 이해
- **배경·문제의식**: 자율주행 인지 모듈(카메라·라이다 기반 객체 인식)은 학습 데이터에 없는 상황(엣지 케이스)에서 오분류할 위험이 있어 전통적 고장 모델로는 검증이 어려움
- **작동 원리**: AI 컴포넌트 고유의 위험 요인으로 학습 데이터 편향·불충분한 커버리지, 분포 외 입력(out-of-distribution) 대응, 모델 업데이트에 따른 성능 변화 등을 식별하고 관리 절차를 요구함
- **작동 원리**: ISO 26262(하드웨어·소프트웨어의 체계적/랜덤 고장 관리), ISO 21448 SOTIF(고장 없이도 발생하는 성능 한계 관리)와 상호 보완적으로 적용되어, AI 컴포넌트가 포함된 자율주행 시스템의 안전 케이스를 구성함
- **비유**: 신입사원 채용 시 이력서 위조 여부(고장)뿐 아니라 실제 업무 판단력(성능 한계)까지 검증하는 것에 더해, 처음 겪는 돌발 상황에서의 대처 능력(AI 고유 위험)까지 평가하는 3단 검증 체계와 같다
- **구체 예시**: 야간·역광·안개 등 학습 데이터에 부족한 환경 조건에서 보행자 인식률이 급락하는 시나리오를 식별하고, 데이터 커버리지 보완과 모니터링 지표로 관리하는 절차가 다뤄짐
- **흔한 오해·주의점**: ISO/PAS 8800은 ISO 26262·21448을 대체하는 표준이 아니라 AI 컴포넌트 특유의 위험을 보완하는 문서이며, 최신 표준이므로 세부 요구사항 인용 시 발간 시점과 정식 ISO 표준 전환 여부를 확인해야 함

## 연결 개념
- ISO 26262 — 자동차 기능안전(하드웨어·소프트웨어 고장 관리)
- ISO 21448 SOTIF — 고장 없는 성능 한계(의도된 기능의 안전) 관리
- NIST AI RMF — AI 위험관리 접근의 산업 공통 원칙과의 연계

## Ⅰ. 개요 및 필요성

- 개요: 자율주행 AI·머신러닝 컴포넌트의 데이터·모델 특유 위험을 다루는 ISO 공개표준초안(PAS)
- 배경: ISO 26262(고장), ISO 21448 SOTIF(성능 한계)가 다루지 못하는 데이터 기반 확률적 판단의 위험이 존재함
- 필요성: 학습 데이터 편향, 분포 외 입력 대응, 모델 업데이트에 따른 성능 변화를 체계적으로 검증·관리할 절차가 필요함

---

## Ⅱ. 구조 및 구성요소

```text
자율주행 안전 요구 -> 위험 유형 분류
  -> ISO 26262: 하드웨어/소프트웨어 고장 관리
  -> ISO 21448 SOTIF: 고장 없는 성능 한계 관리
  -> ISO/PAS 8800: AI/ML 데이터·모델 고유 위험 관리
  -> 통합 안전 케이스 구성
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| ISO 26262 | 체계적/랜덤 하드웨어·소프트웨어 고장 관리 | ASIL 등급 기반 기능안전 |
| ISO 21448 SOTIF | 고장 없이 발생하는 성능 한계 관리 | 의도된 기능의 안전(Safety Of The Intended Functionality) |
| ISO/PAS 8800 | AI/ML 컴포넌트의 데이터·모델 고유 위험 관리 | 데이터 커버리지, 분포 외 입력, 모델 갱신 관리 |
| 통합 안전 케이스 | 세 표준을 결합한 자율주행 안전 논증 | 인지-판단-제어 전 구간 커버 |

> 요약: 세 표준이 고장, 성능 한계, AI 고유 위험을 각각 담당해 자율주행 통합 안전 케이스를 구성한다.

## Ⅲ. 동작원리 및 흐름도

```text
AI 컴포넌트 식별 -> 데이터 커버리지 분석
  -> 분포 외 입력 시나리오 식별
  -> 모델 검증·테스트(엣지 케이스 포함)
  -> 배포 후 모니터링 -> 모델 업데이트 시 재검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 컴포넌트와 학습 데이터 범위 식별 | 데이터 커버리지 지표 |
| 2 | 분포 외 입력·엣지 케이스 시나리오 도출 | 시나리오 목록 완결성 |
| 3 | 모델 성능 테스트 및 안전 여유 확인 | 인식률, 오탐/미탐율 |
| 4 | 배포 후 실사용 데이터 모니터링, 갱신 시 재검증 | 모니터링 지표, 재검증 이력 |

> 요약: 데이터 커버리지 분석과 분포 외 입력 시나리오 검증을 반복하며 모델 갱신 시마다 재검증한다.

## Ⅳ. 특징

| 구분 | ISO 26262 | ISO 21448 SOTIF | ISO/PAS 8800 | 판단 포인트 |
|:---|:---|:---|:---|:---|
| 대상 위험 | 하드웨어/소프트웨어 고장 | 고장 없는 성능 한계 | AI/ML 데이터·모델 고유 위험 | 세 표준은 대체가 아닌 보완 관계 |
| 핵심 활동 | ASIL 등급 분류, 고장 분석 | 알려진/미지 위험 시나리오 관리 | 데이터 커버리지, 분포 외 입력 관리 | AI 컴포넌트는 8800 관점 추가 필요 |
| 표준 성숙도 | 확정 국제표준 | 확정 국제표준 | PAS(공개표준초안), 정식 표준 전환 진행 중 | 인용 시 발간 시점 확인 필요 |

> 요약: 자율주행 안전은 고장 관리, 성능 한계 관리, AI 고유 위험 관리 세 층위를 모두 충족해야 완성된다.

|:---|:---|:---|:---|:---|

| 검증 방법 | 코드 리뷰, 단위 테스트 | 시나리오 기반 테스트 | 데이터셋 커버리지 분석, 적대적 테스트 | 학습 데이터 다양성 확보가 선행 조건 |
| 리스크 | 고장 미탐지 | 엣지 케이스 누락 | 분포 외 상황 오판 | 세 관점을 결합한 통합 안전 케이스 필요 |

> 요약: AI 컴포넌트가 포함된 자율주행 시스템은 전통 SW 검증과 SOTIF에 더해 ISO/PAS 8800 관점의 데이터·모델 검증을 결합해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 데이터 편향 | 특정 환경·인구 집단 데이터 부족 | 데이터 다양성 확보, 커버리지 분석 | 시나리오별 데이터 비율 |
| 분포 외 오판 | 학습 범위 밖 입력 대응 미흡 | 적대적 테스트, 이상탐지 모니터링 | 미탐/오탐율 |
| 모델 갱신 리스크 | 재학습 후 성능 회귀 미검증 | 갱신 시 회귀 테스트 의무화 | 갱신 전후 성능 비교 결과 |

> 요약: AI 안전 리스크는 데이터 다양성 확보, 적대적 테스트, 모델 갱신 회귀 테스트로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 커버리지 | 주요 시나리오별 데이터 비율 목표치 충족 | 데이터셋 분석 리포트 |
| 분포 외 대응 | 엣지 케이스 테스트 통과율 목표치 | 시뮬레이션·실차 테스트 |
| 모델 안전성 | 갱신 후 안전 성능 저하 0건 | 회귀 테스트 결과 비교 |

> 요약: 도입 후 성공 여부는 데이터 커버리지, 엣지 케이스 통과율, 모델 갱신 회귀 테스트 결과로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단기: 자율주행 AI 컴포넌트의 학습 데이터 커버리지를 분석하고 부족 시나리오를 식별함
2. 중기: ISO 26262·21448 안전 케이스에 ISO/PAS 8800 관점의 데이터·모델 위험 평가를 통합함
3. 장기: 모델 갱신 시 회귀 테스트와 모니터링 지표를 자동화해 지속적 안전성을 확보함

**결론 (2줄):**
- 기술사 판단: AI 컴포넌트가 포함된 자율주행 시스템은 ISO 26262·SOTIF·PAS 8800을 결합한 통합 안전 케이스로 검증해야 함
- 향후 방향: ISO/PAS 8800이 정식 ISO 국제표준으로 전환되는 추이를 지속 모니터링하며 국내 인증 체계에 반영해야 함
