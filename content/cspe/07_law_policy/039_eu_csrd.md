# 📖 【암기용】 개념 완전 이해

> 목적: CSRD를 처음 봐도 왜 대기업이 재무제표만이 아니라 ESG 데이터까지 감사 수준으로 공시해야 하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: EU 대기업과 상장 중소기업에 환경·사회·지배구조(ESG) 정보를 유럽지속가능성보고표준(ESRS)에 따라 재무정보 수준으로 공시하도록 의무화한 지침
- **왜 필요한가**: 자율적 ESG 보고서는 기업마다 기준이 달라 투자자·이해관계자가 비교·검증하기 어려웠고 그린워싱 우려가 커졌다
- **핵심 직관**: 재무제표를 회계기준에 맞춰 감사받듯 ESG 정보도 표준화된 기준과 검증 절차를 거쳐 공시해야 한다는 발상이다

## 깊이 이해
- **배경·문제의식**: 기존 비재무보고지침(NFRD)은 적용 대상이 좁고 보고 기준이 느슨해 기업 간 비교가 어려웠다
- **배경·문제의식**: 자율 프레임워크(GRI 등)는 참여가 임의적이라 정보 신뢰성과 일관성이 부족했다
- **작동 원리**: 이중 중대성 평가로 기업이 환경·사회에 미치는 영향(impact materiality)과 지속가능성 이슈가 기업 재무에 미치는 영향(financial materiality)을 함께 평가한다
- **작동 원리**: ESRS라는 공통 공시 기준에 따라 정량·정성 지표를 구조화해 보고한다
- **작동 원리**: 초기에는 제한적 인증(limited assurance)을 받고 향후 합리적 인증(reasonable assurance) 수준으로 강화하는 로드맵을 따른다
- **작동 원리**: NFRD 대비 적용 대상을 대기업과 상장 중소기업까지 단계적으로 확대한다
- **비유**: 회계감사인이 재무제표를 검증하듯 ESG 데이터도 외부 검증인의 인증을 받아야 신뢰할 수 있는 공시가 된다
- **구체 예시**: 제조기업이 탄소배출량을 공시할 때 자사 배출이 환경에 미치는 영향(impact)과 탄소가격 정책이 자사 재무에 미치는 영향(financial)을 모두 평가해 이중 중대성 결과로 보고한다
- **구체 예시**: 공급망 인권 실사 데이터를 ESRS 사회 지표에 맞춰 수집하려면 협력사 데이터 수집 시스템과 데이터 계보 관리가 필요하다
- **흔한 오해·주의점**: CSRD는 사이버보안 규정이 아니라 지속가능성 공시 규정이며 IT 부서 역할은 데이터 수집·검증 시스템 구축에 한정된다
- **흔한 오해·주의점**: 이중 중대성은 둘 중 하나만 평가하면 되는 것이 아니라 impact와 financial 두 축을 모두 평가해야 성립한다

## 연결 개념
- ESG 데이터 거버넌스 — 지속가능성 데이터 수집·검증 체계
- IT 시스템의 지속가능성 데이터 신뢰성 — 데이터 계보 관리와 감사 대응 시스템
- NFRD(비재무보고지침) — CSRD 이전의 좁은 적용 범위 규정과의 비교 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CSRD 답안은 이중 중대성, ESRS 기준, 인증 수준, IT 데이터 거버넌스 4개 축을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSRD는 대기업과 상장 중소기업에 ESRS 기준에 따른 ESG 공시와 외부 검증을 의무화한 EU 지침이다.
> 2. **가치**: 자율적이던 ESG 보고를 표준화·검증 가능한 체계로 전환해 그린워싱 리스크와 정보 비교불가능성을 줄인다.
> 3. **판단 포인트**: 이중 중대성 평가 결과, 인증 수준(limited/reasonable), 데이터 수집 시스템 성숙도를 기준으로 공시 신뢰성을 판단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ESG 공시 규제 이해 확인 | 이중 중대성, ESRS, 인증 요구 구조 | CSRD를 사이버보안·ICT 규정으로 오인 |
| 데이터 신뢰성 확보 역량 확인 | 데이터 계보, 검증 가능한 수집 체계 | ESG 데이터를 정성적 서술로만 처리한다고 서술 |
| 적용 범위·단계 이해 확인 | NFRD 대비 확대된 적용 대상과 인증 단계 | limited/reasonable assurance 구분 누락 |

> 요약: 이 문제는 ESG 지표 나열보다 이중 중대성 평가와 데이터 검증 체계를 얼마나 구체적으로 설명하는지가 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: EU 대기업 ESG 공시 의무화 지침
- 배경: NFRD의 좁은 적용 범위와 자율 ESG 보고의 비교불가능성 한계
- 필요성: ESRS 표준화, 이중 중대성 평가, 제한적 인증에서 합리적 인증으로 단계적 강화

---

## Ⅱ. 구조 및 구성요소

```text
Company -> Double Materiality Assessment(Impact + Financial)
  -> ESRS Reporting -> Assurance(Limited -> Reasonable)
  -> Sustainability Report -> Investor/Stakeholder Disclosure
  -> Data Collection System(IT Governance)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 이중 중대성 평가 | impact/financial materiality 동시 평가 | 두 축 모두 평가해야 유효 |
| ESRS | 공통 ESG 공시 기준 | 환경·사회·지배구조 항목 구조화 |
| 인증(Assurance) | 외부 검증인의 신뢰성 확인 | limited에서 reasonable로 강화 로드맵 |
| 데이터 수집 시스템 | ESG 원천 데이터 수집·계보 관리 | IT 거버넌스와 연계 필요 |
| 적용 대상 확대 | NFRD 대비 대기업·상장 중소기업 포함 | 단계적 시행 일정 |

> 요약: CSRD는 이중 중대성 평가, ESRS 표준, 외부 인증, 데이터 수집 체계를 하나의 공시 프로세스로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Materiality Assessment(Impact/Financial) -> Data Collection
  -> ESRS Mapping -> Draft Sustainability Report
  -> External Assurance Review -> Disclosure Publication
  -> Stakeholder Feedback -> Next Cycle Update
```

| 단계 | 처리 내용 | 검증 기준 |
|:---|:---|:---|
| 1 | 이중 중대성 평가로 공시 항목 선정 | impact/financial 두 축 근거 문서화 |
| 2 | ESRS 항목별 데이터 수집 | 데이터 출처와 계보 추적 가능 여부 |
| 3 | 지속가능성 보고서 초안 작성 | ESRS 구조 준수 여부 |
| 4 | 외부 인증인 검토 | limited/reasonable assurance 수준 |
| 5 | 공시 후 다음 주기 반영 | 전기 대비 지표 일관성 |

> 요약: CSRD 이행은 중대성 평가로 항목을 정하고 데이터 수집과 외부 인증을 거쳐 공시하는 순환 구조다.

## Ⅳ. 특징

| 구분 | 내용 | NFRD/자율 프레임워크(GRI 등) | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 적용 대상 | 대기업, 상장 중소기업 | NFRD는 일부 대기업 한정 | 단계적 적용 확대 일정 |
| 보고 기준 | ESRS 표준화 항목 | GRI 등 임의 프레임워크 | 환경·사회·지배구조 세부지표 |
| 평가 방식 | 이중 중대성(impact+financial) | 단일 관점 또는 자율 선택 | 두 축 근거 문서화 필수 |
| 검증 수준 | 외부 인증 의무 | 자율 보고, 검증 임의 | limited -> reasonable assurance |

> 요약: CSRD는 NFRD·자율 프레임워크 대비 적용 범위, 평가 방식, 검증 강도를 모두 표준화·의무화한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안(NFRD, GRI 등 자율 프레임워크) | CSRD | 선택 기준 |
|:---|:---|:---|:---|
| 적용 범위 | NFRD는 좁은 대기업군 한정 | 대기업·상장 중소기업으로 확대 | 기업 규모·상장 여부 기준 |
| 평가 관점 | 단일 관점(주로 재무 영향) 중심 | 이중 중대성(impact+financial) | 이해관계자 범위와 투자자 요구 |
| 신뢰성 확보 | 자율 보고, 검증 임의 | 외부 인증 의무, 단계적 강화 | 감사 대응 데이터 체계 보유 여부 |

> 요약: 상장 대기업은 자율 프레임워크의 임의성에서 벗어나 CSRD의 이중 중대성과 외부 인증 요건을 충족해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 데이터 신뢰성 부족 | ESG 원천 데이터 계보 미관리 | 데이터 거버넌스 체계, 데이터 계보 추적 시스템 구축 | 데이터 출처 추적 가능 비율 |
| 중대성 평가 누락 | impact/financial 중 한 축만 평가 | 이중 중대성 평가 절차 표준화 | 평가 문서 완결성 점검 |
| 인증 실패 | 검증 가능한 근거 자료 부재 | 외부 인증 대응 데이터 패키지 사전 준비 | 인증 지적사항 수 |

> 요약: CSRD 리스크는 데이터 신뢰성, 중대성 평가 누락, 인증 대응 미비 세 축으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 계보 추적률 | ESRS 핵심 지표 데이터 출처 100% 추적 | 데이터 거버넌스 감사 |
| 이중 중대성 완결성 | impact/financial 두 축 평가 문서화율 | 중대성 평가 보고서 검토 |
| 인증 수준 | limited에서 reasonable로 단계적 전환 | 외부 인증 보고서 확인 |

> 요약: 도입 성과는 데이터 계보 추적률, 이중 중대성 평가 완결성, 인증 수준 전환 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 이중 중대성 평가 절차를 표준화하고 impact·financial 두 축의 근거 문서를 사전에 구축함
2. ESG 원천 데이터 수집을 위한 IT 데이터 거버넌스 체계를 마련하고 데이터 계보 추적 시스템을 구축함
3. 외부 인증 대응 데이터 패키지를 사전 준비해 limited assurance에서 reasonable assurance로의 전환에 대비함

**결론 (2줄):**
- 기술사 판단: CSRD는 ESG 보고를 자율 서술에서 재무제표 수준의 검증 가능한 공시 체계로 전환한 규정으로 이해해야 함
- 향후 방향: ESG 데이터 수집·계보 관리를 IT 시스템 설계 단계부터 내재화해 인증 강화 로드맵에 선제 대응해야 함
