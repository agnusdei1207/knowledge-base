# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: IT 아웃소싱은 **기업이 IT 업무·시스템 운영을 외부 전문 사업자에게 위탁하는 경영 전략**이며, **MSP(Managed Service Provider, 관리형 서비스 제공자)**는 그중에서도 클라우드·인프라·보안을 원격에서 **지속 운영·관리**하는 사업자를 뜻한다. 핵심은 '단발성 개발 위탁'이 아니라 **SLA(서비스수준협약)** 기반으로 운영을 상시 책임진다는 점이다.
- **왜 필요한가**: 기업은 IT를 직접 다 운영하면 인력·전문성·투자 부담이 크다. 비핵심(non-core) 운영을 전문 사업자에게 맡겨 **핵심 역량에 집중**하고, 고정비를 변동비로 바꾸며, 24×365 운영·보안 전문성을 확보한다. 클라우드 확산으로 '구축 대행'을 넘어 '지속 운영 대행(MSP)' 수요가 커졌다.
- **핵심 직관**: 아웃소싱은 '외식·가사도우미'와 같다. 집밥(자체 운영)을 다 하기 벅차면 전문 업체에 맡기되, '무엇을·어느 수준으로·얼마에' 할지 계약(SLA)으로 못 박아야 한다. MSP는 그중 '매일 청소·관리까지 상시 대행'하는 정기 구독형 서비스에 해당한다.

## 핵심 용어 정리
답안에 등장하는 상위 키워드와 내부 용어를 먼저 이해한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| IT 아웃소싱 | IT 업무·운영을 외부에 위탁하는 전략 | 외식·가사 위탁 |
| MSP | 클라우드·인프라를 지속 운영·관리하는 사업자 | 정기 관리 대행업체 |
| SLA(서비스수준협약) | 서비스 품질 목표를 수치로 약정한 계약 | 품질 보증서 |
| SLM(서비스수준관리) | SLA를 지속 측정·개선하는 관리 활동 | 품질 점검 순환 |
| 가용성(Availability) | 서비스가 정상 동작하는 시간 비율 | 99.9% 가동 약속 |
| 핵심 역량 집중 | 비핵심을 위탁하고 본업에 집중 | 요리 대신 영업 |
| Captive/토탈아웃소싱 | 자회사화 / 전체 IT 일괄 위탁 | 부분 vs 통째 위탁 |
| SI vs MSP | 구축(1회성) vs 운영(지속) | 집 짓기 vs 관리 |
| 벤더 락인(Lock-in) | 특정 사업자에 종속돼 이탈 곤란 | 갈아타기 어려움 |
| Exit Plan | 계약 종료·전환 대비 이관 계획 | 이사 대비 계획 |
| MSA(기본계약서) | 위탁의 권리·책임을 정한 마스터 계약 | 거래 기본 약관 |
| 페널티/크레딧 | SLA 미달 시 배상·요금 감면 조항 | 지연 배상금 |

## 깊이 이해
- **배경·문제의식**: IT가 복잡·고도화되며 기업이 서버·네트워크·보안·클라우드를 모두 자체 인력으로 운영하기 어려워졌다. 1990년대 토탈아웃소싱(전체 IT 위탁)에서 시작해, 클라우드 시대엔 **MSP**가 부상했다. 단순 '구축(SI)'은 끝나면 관계가 종료되지만, 운영은 매일 장애·보안·비용 최적화를 상시 책임져야 해 계약 성격이 근본적으로 다르다.
- **작동 원리(어떻게+왜)**: 아웃소싱은 ① 대상 선정(비핵심 식별) → ② 사업자 선정·계약(MSA+SLA) → ③ 이관·운영 → ④ SLM(성과 측정·개선) → ⑤ 계약 갱신 또는 Exit의 생애주기로 돈다. 핵심은 **SLA**로 가용성·응답시간·복구시간(RTO)을 수치화하고 미달 시 페널티/크레딧을 걸어 품질을 강제하는 것이다. MSP는 여기에 클라우드 비용 최적화(FinOps)·보안 관제까지 상시 수행한다.
- **비유**: 아파트 관리를 위탁하는 것과 같다. 관리사무소(MSP)에 청소·경비·설비 점검을 맡기되, '엘리베이터 고장 2시간 내 복구' 같은 SLA를 걸고, 미흡하면 관리비를 깎는다. 잘 맞으면 편하지만, 관리사무소만 아는 배관도면(락인)이 쌓이면 교체가 어렵다.
- **구체 예시**: 한 기업이 AWS 인프라 운영을 MSP에 맡기면, MSP는 24×365 모니터링·장애 대응·비용 최적화·보안 패치를 수행하고, 'CPU 장애 30분 내 대응·월 가용성 99.9%'를 SLA로 약정한다. 미달 시 월 요금의 일정 %를 크레딧으로 감면한다. 공공은 '위탁운영' 시 정보보안·개인정보 위수탁 계약을 별도로 맺는다.
- **흔한 오해·주의점**: ① **아웃소싱 ≠ 책임 이전** — 운영을 위탁해도 데이터·보안의 최종 책임(위탁자 책임)은 발주사에 남는다(개인정보 위수탁, 024 참조). ② **SI = MSP가 아니다** — SI는 1회성 구축, MSP는 지속 운영으로 계약·과금이 다르다. ③ **저비용만 보면 위험** — 벤더 락인·품질 저하로 총소유비용(TCO)이 되레 커질 수 있어 Exit Plan·SLA가 필수다.

## 연결 개념
- 클라우드컴퓨팅법 (029 참조): MSP가 다루는 클라우드 서비스의 이용·보안 법적 틀
- 개인정보보호법 (024 참조): 운영 위탁 시 개인정보 위수탁·수탁자 관리·감독 의무
- ITIL·ITSM (006 참조): SLA·SLM 등 서비스 수준 관리의 프로세스 프레임워크

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 아웃소싱은 IT 운영을 외부에 위탁하는 전략이고, MSP는 클라우드·인프라를 SLA 기반으로 지속 운영·관리하는 사업자임.
> 2. **가치**: 비핵심 운영 위탁으로 핵심 역량에 집중하고 고정비를 변동비로 전환하며 24×365 전문 운영·보안을 확보함.
> 3. **판단 포인트**: 위탁해도 데이터·보안 최종 책임은 발주사에 남으므로, SLA·페널티·Exit Plan으로 품질과 락인을 통제해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개념 구분 이해 | 아웃소싱(위탁)·MSP(지속운영)·SI(구축) 구분 | SI와 MSP를 동일시 |
| 계약 관리 이해 | SLA·SLM·페널티/크레딧 체계 | SLA 없이 품질 담보 단정 |
| 리스크 관리 이해 | 위탁자 책임·벤더 락인·Exit Plan | 위탁으로 책임 이전 단정 |

> 요약: 아웃소싱·MSP·SI를 구분하고 SLA/SLM 관리와 위탁자 책임·락인·Exit Plan을 함께 짚어야 함.

## Ⅰ. 개요 및 필요성

- 개요: IT 아웃소싱은 IT 운영을 외부에 위탁하는 전략, MSP는 SLA 기반 지속 운영 사업자임
- 배경: IT 고도화·클라우드 확산으로 자체 운영의 인력·전문성 부담이 커짐
- 필요성: 비핵심 운영 위탁으로 핵심 역량 집중과 24×365 전문 운영·보안 확보가 필요
- 통제: 위탁해도 데이터·보안 책임이 남아 SLA·Exit Plan으로 품질·종속을 통제할 필요

---

## Ⅱ. 구조 및 구성요소

```text
[발주사(위탁자)] -> [MSA 기본계약 + SLA 약정] -> [MSP/아웃소싱 사업자(수탁자)]
      |                                                |
   비핵심 IT 운영 위탁                          클라우드/인프라/보안 지속 운영
      |                                                |
   [SLM 순환] : 목표(SLA) -> 측정 -> 리포트 -> 개선/페널티
      |
   생애주기: 대상선정 -> 계약 -> 이관 -> 운영 -> 갱신 / Exit Plan
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MSA 기본계약 | 권리·책임·범위 마스터 계약 | 개별 SOW 하위 연결 |
| SLA | 가용성·응답·복구 목표 약정 | 미달 시 페널티/크레딧 |
| SLM | SLA 측정·리포트·개선 순환 | ITIL 서비스수준관리 |
| MSP 운영 | 모니터링·장애·보안·비용 최적화 | 24×365 지속 수행 |
| Exit Plan | 종료·전환 시 자산·지식 이관 | 락인 대비 필수 |

> 요약: 위탁자·수탁자가 MSA·SLA로 계약하고 MSP가 지속 운영하며, SLM 순환과 Exit Plan으로 품질·전환을 관리함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[대상 선정: 비핵심 IT 식별] -> [사업자 선정·계약: MSA + SLA]
   -> [이관: 자산·운영 지식 인수] -> [운영: 24x365 모니터링·장애·보안]
   -> [SLM: 성과 측정·리포트·페널티] -> [갱신 또는 Exit Plan 실행]
```

- 1단계 [선정·계약]: 발주사가 비핵심 IT를 식별하고 사업자와 MSA·SLA(가용성·RTO 등)를 약정함
- 2단계 [이관]: 수탁 사업자가 시스템 자산·운영 지식·계정을 인수해 운영 체계를 구축함
- 3단계 [운영]: MSP가 24×365 모니터링·장애 대응·보안 패치·클라우드 비용 최적화를 상시 수행함
- 4단계 [SLM·갱신]: 발주사가 SLA 달성도를 측정·리포트받아 미달 시 페널티를 적용하고 갱신 또는 Exit을 결정함

> 요약: 대상 선정·계약 후 자산을 이관해 MSP가 지속 운영하고, SLM으로 성과를 측정해 갱신 또는 전환을 결정함.

---

## Ⅳ. 특징
- 지속 운영성: 1회성 구축(SI)과 달리 24×365 상시 운영·관리를 책임
- SLA 기반: 가용성·응답·복구시간을 수치로 약정하고 미달 시 페널티/크레딧으로 강제
- 비용 구조 전환: 자체 운영 고정비를 위탁 변동비(구독형)로 전환
- 전문성 확보: 클라우드·보안 등 확보 어려운 전문 인력·관제를 외부에서 조달
- 종속 리스크: 벤더 락인·책임 소재 모호가 상존해 Exit Plan·명확한 R&R이 필요

> 요약: 지속 운영성·SLA 기반·비용 전환·전문성 확보가 강점이나, 락인·책임 모호라는 트레이드오프를 통제해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | SI(시스템 구축) | IT 아웃소싱(운영 위탁) | MSP(관리형 서비스) |
|:---|:---|:---|:---|
| 계약 성격 | 1회성 구축 프로젝트 | 기간제 운영 위탁 | 지속·구독형 운영 |
| 주 대상 | 신규 시스템 개발 | 전체·부분 IT 운영 | 클라우드·인프라·보안 |
| 과금 방식 | 산출물 기준 대가 | 인력·기간 기반 | 사용량·구독 기반 |
| 핵심 관리 | 납기·품질 | SLA·인력 관리 | SLA·비용 최적화(FinOps) |
| 종료 후 관계 | 유지보수로 전환 | 갱신·전환 | 갱신·이관(Exit) |

> 요약: SI는 1회성 구축, 아웃소싱은 기간제 운영 위탁, MSP는 클라우드 지속 운영으로 계약·과금·관리 초점이 다름.

**리스크·대응(리스크 — 원인 — 대응):**
- 벤더 락인 — 특정 사업자 기술·지식 종속 — 표준 기술·멀티벤더·Exit Plan으로 전환성 확보
- 책임 모호 — 위탁으로 책임 이전 오인 — 위탁자 책임 명문화·개인정보 위수탁 계약(024)
- 품질 저하 — SLA 없는 저가 계약 — SLA·페널티/크레딧과 정기 SLM 리포트로 강제

**적용 판단 지표(지표 — 목표 — 측정):**
- 가용성 — 월 99.9% 이상 유지 — 다운타임·SLA 달성률 측정
- 대응시간 — 장애 30분 내 대응·RTO 준수 — 티켓 응답·복구시간 추적
- 비용 효율 — 클라우드 TCO 절감 — FinOps 절감액·유휴 리소스율 측정

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 계약 설계: MSA에 범위·R&R을 명확히 하고 SLA에 가용성 99.9%·RTO·응답시간을 수치화하며 미달 시 크레딧을 걸어 품질을 강제
2. 락인 대비: 표준 기술·멀티클라우드를 전제로 계약하고 자산·운영 문서·계정 인수를 포함한 Exit Plan을 사전에 확보해 전환 리스크를 낮춤
3. 책임·보안 관리: 위탁자 책임을 전제로 개인정보 위수탁 계약(024)과 수탁자 관리·감독, 보안 관제 SLA를 넣어 데이터 보호 최종 책임을 이행

**결론 (2줄):**
- 기술사 판단: 핵심·민감 시스템은 통제권을 유지하며 부분 위탁하고, 비핵심·클라우드 운영은 SLA 기반 MSP로 전환해 전문성과 비용 효율을 얻는 선별 전략이 합리적임.
- 향후 방향: 클라우드·AI 운영 복잡도가 커지므로 단순 위탁을 넘어 FinOps·보안 관제를 포함한 MSP로 고도화하되, Exit Plan과 위탁자 책임 체계를 상시 유지해야 함.
