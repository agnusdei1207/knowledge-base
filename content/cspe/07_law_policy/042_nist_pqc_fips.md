# 📖 【암기용】 개념 완전 이해

> 목적: NIST PQC 표준을 처음 봐도 왜 만들어졌고 세 표준이 각각 무엇을 하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 양자 컴퓨터로도 안전한 공개키 암호를 NIST가 표준화한 PQC(Post-Quantum Cryptography) 표준군, 2024년 FIPS 203·204·205 확정
- **왜 필요한가**: Shor 알고리즘으로 양자 컴퓨터가 RSA·ECC의 소인수분해·이산로그 문제를 다항 시간에 풀 수 있어 기존 공개키 암호가 무력화될 위험이 있음
- **핵심 직관**: 자물쇠 회사가 만능 열쇠(양자 컴퓨터) 등장에 대비해 열쇠 구조 자체가 다른 새 자물쇠(격자·해시 기반 암호)로 미리 교체하는 것과 같음

## 깊이 이해
- **배경·문제의식**: 지금 암호화한 데이터를 저장했다가 미래 양자 컴퓨터로 복호화하는 "Harvest Now, Decrypt Later" 공격 위험이 존재함
- **배경·문제의식**: NIST는 2016년부터 공모를 시작해 격자 기반, 해시 기반 등 수학적 난제가 다른 여러 후보를 검증함
- **작동 원리**: FIPS 203(ML-KEM)은 CRYSTALS-Kyber 기반 키 캡슐화 메커니즘으로 통신 양측이 공유 비밀키를 교환하는 데 사용함
- **작동 원리**: FIPS 204(ML-DSA)는 CRYSTALS-Dilithium 기반 전자서명으로 메시지 위변조 방지와 서명자 인증에 사용함
- **작동 원리**: FIPS 205(SLH-DSA)는 SPHINCS+ 기반 상태 비저장(stateless) 해시 기반 전자서명으로, 격자 문제와 다른 해시 함수의 안전성에 의존하는 대체 서명 방식임
- **비유**: ML-KEM은 두 사람이 안전하게 열쇠를 나눠 갖는 방법이고, ML-DSA·SLH-DSA는 문서에 위조 불가능한 도장을 찍는 방법이다
- **구체 예시**: TLS 1.3 핸드셰이크에서 서버와 클라이언트가 ML-KEM으로 세션키를 교환하고, 서버 인증서 서명은 ML-DSA로 검증하는 하이브리드 구성이 실무에서 검토됨
- **흔한 오해·주의점**: ML-KEM은 암·복호화가 아닌 키 교환(키 캡슐화) 표준이며, 데이터 자체를 암호화하는 대칭키 알고리즘(AES)을 대체하는 것이 아님
- **흔한 오해·주의점**: SLH-DSA는 ML-DSA보다 서명·검증 속도가 느리고 서명 크기가 크지만, 격자 문제가 아닌 해시 함수 안전성에 기반해 수학적 난제가 달라 백업 알고리즘으로 병행 표준화됨

## 연결 개념
- Shor 알고리즘 — 양자 컴퓨터가 RSA·ECC를 위협하는 근거
- 암호 민첩성(Crypto-Agility) — 알고리즘 교체가 쉬운 시스템 설계 원칙
- TLS·PKI — PQC 알고리즘이 실제 적용되는 프로토콜 계층

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: NIST PQC 답안은 FIPS 203/204/205의 알고리즘 계열·용도 구분, 양자 위협 근거, 마이그레이션 전략을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NIST PQC는 양자 컴퓨터 공격에 안전한 키 교환·전자서명 알고리즘을 FIPS 203/204/205로 표준화한 것이다.
> 2. **가치**: Shor 알고리즘에 의한 RSA·ECC 붕괴 위험과 Harvest Now, Decrypt Later 공격에 선제 대응한다.
> 3. **판단 포인트**: 키 교환은 ML-KEM(FIPS 203), 서명은 격자 기반 ML-DSA(FIPS 204)를 기본으로 하고 SLH-DSA(FIPS 205)는 수학적 난제가 다른 백업 서명으로 병행한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PQC 표준 구조 이해 확인 | FIPS 203/204/205와 원조 알고리즘(Kyber/Dilithium/SPHINCS+) 매칭 | FIPS 번호와 알고리즘·용도(KEM vs 서명)를 뒤바꿔 서술 |
| 양자 위협 근거 이해 확인 | Shor 알고리즘, Harvest Now Decrypt Later | "양자 컴퓨터가 위험하다"는 추상 서술만 사용 |
| 마이그레이션 실무 판단 확인 | 하이브리드 적용, 암호 민첩성, 성능·크기 트레이드오프 | 전환 전략 없이 표준 나열만 서술 |

> 요약: 이 문제는 세 표준의 이름 나열이 아니라 FIPS 번호-알고리즘 계열-용도(키 교환 vs 서명)의 정확한 매칭이 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: 양자 컴퓨터 공격에 안전한 공개키 암호를 NIST가 확정한 FIPS 203·204·205 표준군
- 배경: 2024년 8월 FIPS 203(ML-KEM), FIPS 204(ML-DSA), FIPS 205(SLH-DSA) 공식 발표
- 필요성: Shor 알고리즘 기반 양자 공격과 저장 후 미래 복호화 공격에 대비해 RSA·ECC를 대체할 표준이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
양자 위협(Shor 알고리즘) -> PQC 표준 선정
  -> FIPS 203 ML-KEM(키 캡슐화, Kyber 기반)
  -> FIPS 204 ML-DSA(전자서명, Dilithium 기반)
  -> FIPS 205 SLH-DSA(전자서명, SPHINCS+ 기반)
  -> TLS/PKI 적용 -> 하이브리드 마이그레이션
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| FIPS 203 ML-KEM | 키 캡슐화, 통신 양측 공유 비밀키 교환 | 원조: CRYSTALS-Kyber, 격자 기반 |
| FIPS 204 ML-DSA | 전자서명, 메시지 위변조 방지·인증 | 원조: CRYSTALS-Dilithium, 격자 기반 |
| FIPS 205 SLH-DSA | 전자서명, 상태 비저장 해시 기반 백업 서명 | 원조: SPHINCS+, 해시 함수 기반 |
| 하이브리드 구성 | 기존 RSA/ECC와 PQC 알고리즘 병행 적용 | 전환 기간 리스크 완화 |

> 요약: 키 교환은 ML-KEM 하나, 서명은 격자 기반 ML-DSA와 해시 기반 SLH-DSA 두 계열로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
알고리즘 선정 -> 키 교환/서명 목적 구분
  -> ML-KEM으로 세션키 캡슐화
  -> ML-DSA 또는 SLH-DSA로 서명·검증
  -> 하이브리드 핸드셰이크 적용 -> 성능·크기 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 용도 구분(키 교환 vs 서명) | 프로토콜 요구사항 |
| 2 | ML-KEM으로 공유 비밀키 캡슐화·복호화 | 캡슐화 성공률, 핸드셰이크 지연 |
| 3 | ML-DSA 또는 SLH-DSA로 서명 생성·검증 | 서명 크기, 검증 시간 |
| 4 | 기존 RSA/ECC와 하이브리드 병행 적용 | 상호운용성, 롤백 가능 여부 |

> 요약: 키 교환은 ML-KEM 한 단계로 처리되고, 서명은 알고리즘 특성에 따라 ML-DSA 또는 SLH-DSA를 선택해 검증한다.

---

## Ⅳ. 특징

| 구분 | FIPS 203 ML-KEM | FIPS 204 ML-DSA | FIPS 205 SLH-DSA | 판단 포인트 |
|:---|:---|:---|:---|:---|
| 용도 | 키 캡슐화(키 교환) | 전자서명 | 전자서명(백업) | KEM과 서명은 다른 알고리즘군 |
| 수학적 기반 | 격자(Module-LWE) | 격자(Module-LWE/SIS) | 해시 함수 | 격자 문제 취약 시 SLH-DSA로 대체 |
| 성능 특성 | 키 크기 작고 속도 빠름 | 서명 크기 중간, 속도 빠름 | 서명 크기 크고 속도 느림 | 실시간 서비스는 ML-DSA 우선 |
| 원조 알고리즘 | CRYSTALS-Kyber | CRYSTALS-Dilithium | SPHINCS+ | 이름 혼동 시 즉시 감점 |

> 요약: FIPS 203은 키 교환, FIPS 204·205는 서명이며 205는 격자 문제와 무관한 해시 기반 백업이라는 점이 핵심 구분이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 RSA/ECC | ML-KEM/ML-DSA(격자) | SLH-DSA(해시) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 양자 내성 | Shor 알고리즘에 취약 | 격자 문제 기반으로 양자 내성 확보 | 해시 함수 기반으로 양자 내성 확보 | 신규 시스템은 격자 기반 우선 적용 |
| 성능/비용 | 키·서명 크기 작음 | 키·서명 크기 다소 증가 | 서명 크기·연산량 크게 증가 | 대역폭 제약 시 ML-KEM/ML-DSA 우선 |
| 운영/위험 | 양자 위협 노출 | 격자 문제 미래 취약점 가능성 존재 | 수학적 난제가 달라 이중 안전판 역할 | 고위험 서명은 SLH-DSA 병행 검토 |

> 요약: 신규 구축은 격자 기반 ML-KEM·ML-DSA를 기본으로 하고, 격자 문제 취약 가능성에 대비해 SLH-DSA를 백업 서명으로 병행한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Harvest Now Decrypt Later | 현재 암호문 저장 후 미래 양자 복호화 | 장기 보관 데이터부터 PQC 우선 적용 | PQC 적용률, 데이터 보관 기간 |
| 알고리즘 혼동 적용 | FIPS 번호·용도 오인으로 서명에 KEM 알고리즘 오적용 | 프로토콜 표준 준수, 코드 리뷰 | 표준 준수 점검 결과 |
| 성능 저하 | PQC 키·서명 크기 증가로 지연 발생 | 하이브리드 적용, 캐시·세션 재사용 최적화 | 핸드셰이크 지연, TPS 변화 |

> 요약: PQC 도입 리스크는 장기 저장 데이터 우선순위, 알고리즘 용도 오적용 방지, 성능 지표 모니터링으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 적용 범위 | 핵심 시스템 PQC 전환율 목표치 | 자산 인벤토리, 적용 현황판 |
| 성능 | 핸드셰이크 지연 증가폭 허용 범위 이내 | 벤치마크, APM |
| 상호운용성 | 하이브리드 모드 롤백 가능 여부 | 상호운용 테스트 결과 |

> 요약: 도입 후 성공 여부는 PQC 전환율, 성능 지연폭, 하이브리드 상호운용성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단기: 암호 자산 인벤토리를 수립하고 장기 보관 데이터부터 ML-KEM 기반 키 교환을 우선 적용함
2. 중기: TLS·PKI 인증서 서명을 ML-DSA로 전환하고 고위험 영역에는 SLH-DSA를 백업 서명으로 병행함
3. 장기: 암호 민첩성을 확보해 알고리즘 취약점 발견 시 신속히 교체 가능한 구조로 표준화함

**결론 (2줄):**
- 기술사 판단: 키 교환은 FIPS 203 ML-KEM, 서명은 FIPS 204 ML-DSA를 기본으로 하고 FIPS 205 SLH-DSA는 수학적 난제 분산을 위한 병행 표준으로 채택함
- 향후 방향: 하이브리드 암호 체계에서 순수 PQC 체계로 단계적 전환하며 암호 민첩성 거버넌스를 구축해야 함
