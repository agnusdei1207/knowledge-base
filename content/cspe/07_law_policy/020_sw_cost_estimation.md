## 미리 알고가기

- 기능점수(FP): 사용자가 받는 기능 규모를 기준으로 개발 대가를 산정하는 방식임
- ILF, EIF, EI, EO, EQ: 기능점수 산정에 쓰는 대표 기능 요소임
- 보정계수: 기능 규모만으로 설명되지 않는 복잡도와 비기능 요구를 반영하는 계수임
- AI 사업은 데이터 준비와 모델 학습 공수가 커서 기존 FP만으로 설명하기 어려운 경우가 많음

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 대가 산정은 정보화 사업의 기획, 구축, 운영, 유지보수에 필요한 비용을 기능 규모와 난이도와 직접경비 기준으로 계산하는 체계임
- **배경/필요성**: 공공 SW사업은 요구사항이 바뀌기 쉽고 무형 산출물의 가치가 보이지 않으므로, 예산 과소 산정과 무상 변경을 막을 객관적 기준이 필요함

## Ⅱ. 특징

- 공공 구축사업에서는 투입 인력보다 기능 규모를 기준으로 대가를 산정해 생산성 차이를 일정 부분 흡수함
- 요구사항과 기능 기준선이 분명해야 기능점수 산정과 변경 대가 반영이 일관되게 동작함
- 구축, 운영, 유지관리처럼 사업 단계에 따라 적용 방식과 비용 구성 항목이 달라짐
- AI, 데이터, SaaS 사업처럼 화면과 테이블보다 데이터 준비와 모델 학습 비중이 큰 영역에서는 기존 FP만으로 한계가 드러남

## Ⅲ. 종류 및 비교

| 판단 기준 | 투입공수 방식 | 기능점수 방식 | AI·신기술 보완 기준 |
|:---|:---|:---|:---|
| 산정 기준 | 사람 수와 기간을 중심으로 비용을 계산함 | 사용자가 받는 기능 규모를 중심으로 비용을 계산함 | 데이터 준비, 모델 학습, 튜닝 같은 신기술 공수를 따로 반영함 |
| 장점 | 초기 산정이 단순하고 예외 상황에 쓰기 쉬움 | 산출물 중심이어서 구축 대가의 객관성을 높이기 쉬움 | 기존 FP가 설명하지 못하는 AI 사업 특성을 보완하기 좋음 |
| 한계 | 인력 투입이 많을수록 비용이 커져 생산성 반영이 약함 | 화면과 테이블 중심 기능이 적은 사업에서는 과소 산정될 수 있음 | 기준이 아직 고도화되는 단계라 사업 간 일관성 관리가 필요함 |
| 적합한 상황 | 컨설팅, 연구, 예외적 시스템 SW 사업에 상대적으로 맞음 | 일반적인 정보시스템 구축사업에 기본 기준으로 맞음 | AI, 데이터 분석, 신기술 적용 사업에 보완적으로 맞음 |

> 요약: 대가 산정은 기능점수가 기본이지만 사업 유형에 따라 보완 기준을 함께 써야 실제 공수를 설명할 수 있음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 요구사항 기준선 | 기능 범위가 먼저 고정돼야 기능점수와 변경 대가가 같은 기준으로 계산됨 |
| 기능점수 요소 | ILF, EIF, EI, EO, EQ가 사용자 기능 규모를 나누는 기본 단위가 됨 |
| 단가와 보정계수 | 기능 규모에 표준 단가와 복잡도 보정을 적용해 개발원가를 산정함 |
| 직접경비와 이윤 | 장비, 시험, 출장 같은 직접경비와 계약상 이윤을 더해 총사업비를 구성함 |
| 신기술 보완 항목 | 데이터 정제, 학습, 튜닝, 성능 검증처럼 FP 밖의 공수를 추가로 설명하는 장치임 |

> 요약: 대가 산정은 기능 규모를 중심으로 하되 직접경비와 신기술 보완 항목까지 묶어 총비용을 계산하는 구조임

```text
+-------------+     +---------------+     +-----------------+     +--------------+
| 요구사항 정리 | --> | 기능 규모 산정    | --> | 단가/보정 적용     | --> | 총사업비 확정    |
+-------------+     +---------------+     +-----------------+     +--------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +----------------+
| 요구사항 확정   | --> | 기능 수량 산정  | --> | 비용 요소 합산  | --> | 계약 및 변경 반영  |
+-------------+     +-------------+     +-------------+     +----------------+
```

1. **요구사항 확정**: 발주 전 기능 범위와 비기능 요구를 정리해 산정 기준선을 만듦
2. **기능 수량 산정**: 기능점수 요소를 기준으로 사용자 기능 규모를 계산함
3. **비용 요소 합산**: 단가, 보정계수, 직접경비, 이윤을 더해 총대가를 산출함
4. **계약 및 변경 반영**: 사업 중 변경 요구가 생기면 같은 기준으로 재산정해 계약에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 공공 정보시스템 구축에서는 발주 전에 기능점수 기준선을 명확히 잡지 않으면 예산과 변경 대가가 흔들리므로 ISMP와 FP 산정을 연계하고 초기 산정 대비 변경 증감률과 과업변경 반영률로 확인함
2. AI 챗봇이나 데이터 분석 사업에서는 기존 FP만 적용하면 데이터 정제와 모델 학습 공수가 빠질 수 있으므로 신기술 가이드를 함께 적용하고 모델 학습 공수 반영률과 예산 대비 성능 검증 결과로 확인함

## Ⅶ. 결론

소프트웨어 대가 산정은 기능 규모를 기준으로 공정 대가를 확보하는 체계이므로 기준선 요구사항과 사업 유형별 보완 기준을 함께 관리해야 실제 비용을 설명할 수 있음.
