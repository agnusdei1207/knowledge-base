# 1. 한눈에 보는 SW 대가 산정
- **정의**: 공공/민간 정보화 사업에서 소프트웨어를 기획, 개발, 운영, 유지보수하는 데 드는 적정 비용(예산)을 과학적으로 계산하는 기준과 절차.
- **필요성**: 눈에 보이지 않는 SW의 가치를 객관적으로 평가하여, 발주자의 예산 낭비를 막고 수주자(개발사)가 일한 만큼 제값을 받게 하기 위함.
- **핵심 직관**: "인테리어 견적 뽑기." 평당 단가로 대충 부르는 게 아니라, "방 3개(데이터 기능), 창문 5개(입출력 기능), 조명 10개(인터페이스)"를 꼼꼼히 세어서(기능점수, FP) 표준 단가를 곱해 견적을 내는 것입니다.

# 2. 깊이 이해하기: 대가 산정의 핵심, 기능점수(FP) 방식

SW 사업 단가는 예전엔 **'투입 인력(Headcount/Man-Month) 방식'**을 썼습니다. "초급 개발자 5명이 3달 일하니까 1억 주세요."
→ **문제점**: 실력 좋은 개발자가 1달 만에 빨리 끝내면 돈을 적게 받고, 실력 없는 개발자가 6달 끌면 돈을 많이 받는 **모순**이 발생합니다.

그래서 현재 공공기관의 SW 구축 대가 산정은 **기능점수(FP, Function Point) 방식**이 법적 의무입니다.
- **개념**: 사용자 관점에서 시스템이 제공하는 '기능의 양'을 세는 방식.
- **요소 (5가지)**: 
  - 데이터 기능: **ILF** (내부 논리 파일 - 내 DB), **EIF** (외부 연계 파일 - 남의 DB 참조).
  - 트랜잭션 기능: **EI** (외부 입력 - 화면에서 입력/저장), **EO** (외부 출력 - 계산해서 보여줌), **EQ** (외부 조회 - 있는 그대로 검색).
- **계산식**: `(기능점수 총합) × (기능점수당 단가) × (보정 계수)`

## 2.1 최신 이슈: AI 도입 사업의 대가 산정 한계
요즘 "AI 챗봇 개발 사업"이 많습니다. 그런데 AI 시스템은 화면(EI, EO, EQ)이 별로 없습니다. 
학습 데이터(수백만 건)를 튜닝하고 알고리즘을 최적화하는 데 시간과 돈이 다 들어가는데, 기능점수(FP)는 '화면과 DB 테이블 개수'만 세기 때문에 예산이 터무니없이 적게 나옵니다.
→ **해결책**: 정보통신산업진흥원(NIPA)과 한국SW산업협회(KOSA)에서 **'AI 등 신기술 기반 SW 사업 대가 산정 가이드'**를 새로 발표하여, 데이터 준비, 모델 학습, 튜닝에 대한 별도 대가 기준을 마련 중입니다.

# 3. 관련 키워드와 연결 서사
- **ISMP (정보화 마스터플랜)**: 사업 발주 전 예산을 정확히 뽑기 위해 상세 요구사항을 정의하고 '기능점수(FP)'를 세는 과정이 ISMP입니다.
- **유지관리비**: 개발이 끝나고 매년 운영할 때 주는 돈도 '요율제(구축비의 15% 등)'로 대가를 산정합니다.

# ✍️ 【답안용】 핵심 골격 및 인사이트

## Ⅰ. SW 제값받기의 객관적 척도, SW 대가 산정 제도의 개요
- **본질**: SW 사업의 생명주기(기획-개발-운영) 전반에 걸쳐 소요되는 비용을 투명하고 과학적으로 산출하는 표준 체계.
- **발전 방향**: 투입 인력(M/M) 기반의 원가 보전 방식에서 벗어나, 사용자 관점의 가치/산출물 중심인 **기능점수(FP)** 방식으로 완전 전환 (SW 진흥법 근거).

## Ⅱ. SW 대가 산정의 핵심, 기능점수(FP) 기반 산정 모델
- 투입 공수가 아닌 소프트웨어가 사용자에게 제공하는 논리적 기능의 규모를 측정.
- **기능점수 도출 5대 구성 요소**:
  1. **데이터 기능**: 내부 논리 파일(ILF), 외부 인터페이스 파일(EIF)
  2. **트랜잭션 기능**: 외부 입력(EI), 외부 출력(EO), 외부 조회(EQ)
- **대가 산출 공식**: 
  - `SW 개발비 = 보정 전 개발원가(기능점수 × FP단가) × 보정계수 + 직접경비 + 이윤`
  - (보정계수: 규모, 애플리케이션 복잡도, 보안/다중 사이트, 성능 등 비기능 요건 반영)

## Ⅲ. 단계별 SW 대가 산정 적용 방식 (가이드라인 기준)
1. **기획 단계 (컨설팅)**: ISP, ISMP 등 컨설팅 대가. 보통 투입 공수(M/M) 방식 적용.
2. **구축 단계 (개발)**: **기능점수(FP) 방식** 적용 (단, UI/DB가 없는 시스템 SW 등은 투입공수 예외 적용 가능).
3. **운영 단계 (유지보수)**: 상용SW 유지관리 (라이선스의 15~20% 요율제), 정보시스템 운영비, 재개발 비용(FP 활용).

## Ⅳ. 기존 FP 방식의 한계 및 신기술(AI, 빅데이터) 적용 문제점
- **UI/UX 부재**: AI 모델 개발이나 빅데이터 분석 시스템은 정형화된 입출력 화면(EI/EO/EQ)이나 DB 테이블(ILF)이 적어 FP 규모가 극단적으로 작게 산출됨.
- **알고리즘 복잡도 미반영**: 머신러닝 학습, 데이터 라벨링, 파라미터 튜닝 등에 엄청난 공수가 들어가나, 기존 FP의 '복잡도 보정계수'만으로는 이를 현실적으로 보상 불가.

## Ⅴ. 신기술 환경에 대응하는 차세대 대가 산정 개선 방향 (최신 동향)
- **AI 특화 대가 산정 체계 도입**: 한국SW산업협회(KOSA) 주도, AI 모델의 학습 데이터 규모(볼륨), 레이어 수, 추론 속도(응답 시간) 등 AI 특화 복잡도 지표 개발 및 보정계수 신설.
- **데이터 생명주기 비용 산정**: 데이터 수집, 정제, 전처리(Pre-processing)에 투입되는 별도의 공수를 '데이터 엔지니어링 대가'로 분리 신설.
- **애자일(Agile) & SaaS형 과금 반영**: 요구사항 변경이 잦은 애자일 환경에서는 스토리 포인트(Story Point) 기반 산정이나 Time & Material(시간/자재) 계약 방식, SaaS의 경우 API 호출량/구독형 기준 과금 체계로의 다변화 필요.

> **💡 작성 팁 (문제 유형별 목차 전환)**
> - **'기능점수(FP) 개념' 문제**: Ⅱ의 5대 구성요소(ILF, EIF, EI, EO, EQ)를 정확한 약어와 함께 기술하면 만점.
> - **'최신 이슈/기술사형' 출제**: 무조건 Ⅳ와 Ⅴ를 메인으로 써야 합니다. "AI 시스템을 기존 FP로 쟀더니 예산이 1/10 토막이 났다. 따라서 데이터 전처리와 모델 학습 공수를 반영하는 새로운 AI 대가 체계가 필수적이다"라는 논리가 현재 가장 핫한 출제 토픽입니다.
