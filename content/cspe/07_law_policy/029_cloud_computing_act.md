## 미리 알고가기

- CSAP는 공공기관이 사용할 민간 클라우드 서비스의 보안 수준을 심사하는 제도임
- CSP는 인프라, 플랫폼, 소프트웨어 형태의 클라우드 서비스를 제공하는 사업자임
- SLA는 가용성, 장애 대응, 복구 책임처럼 서비스 수준을 계약으로 명확히 한 기준임
- 클라우드 우선 검토는 공공기관이 정보시스템 구축과 전환 시 클라우드 활용 가능성을 먼저 검토하는 원칙임

## Ⅰ. 개요

- **정의/개념**: 클라우드컴퓨팅법은 클라우드 산업을 육성하고 이용자를 보호하기 위한 기본법이며, 공공부문에서는 클라우드 우선 검토와 보안 검증 체계를 통해 민간 클라우드 활용 기준을 제시함
- **배경/필요성**: 공공기관도 신속한 확장성과 운영 효율이 필요한데 자체 구축만으로는 변화 속도를 따라가기 어렵고, 그렇다고 보안 검증 없는 민간 서비스 사용은 위험하므로 전환 촉진과 보안 통제를 함께 담은 기준이 필요함

## Ⅱ. 특징

- 클라우드 도입을 산업 진흥 과제로 보면서도 이용자 보호와 안정성 책임을 함께 규정함
- 공공기관에 클라우드 우선 검토 원칙을 적용해 전환의 기본 방향을 제시함
- CSAP를 통해 공공용 민간 클라우드의 보안 수준을 사전에 검증함
- 계약, 가용성, 데이터 보호, 서비스 종료 대응처럼 운영 단계의 책임을 중요하게 다룸

## Ⅲ. 종류 및 비교

| 판단 기준 | 자체 구축 중심 방식 | 클라우드컴퓨팅법 기반 공공 클라우드 활용 |
|:---|:---|:---|
| 자원 확보 | 기관이 서버와 스토리지를 직접 도입하고 증설함 | 수요에 따라 민간 클라우드 자원을 빠르게 확장하거나 축소함 |
| 보안 검증 | 기관 내부 기준과 개별 점검에 크게 의존함 | 공공 이용 전 CSAP 같은 사전 보안 검증 체계를 거침 |
| 운영 책임 | 하드웨어, 장애 대응, 교체 주기를 기관이 직접 부담함 | CSP와 기관이 SLA와 역할 분담에 따라 책임을 나눔 |
| 전환 속도 | 신규 서비스와 확장 대응이 상대적으로 느림 | 표준화된 서비스와 자동화 기능으로 전환과 확장이 빠름 |

> 요약: 클라우드컴퓨팅법은 공공 전환 속도와 보안 검증을 함께 관리하는 기준을 제공함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이용 기관 | 공공기관이나 기업이 시스템 특성과 데이터 중요도를 검토해 클라우드 활용 여부를 판단함 |
| CSP | 인프라, 플랫폼, 소프트웨어 서비스를 제공하고 가용성과 보안 운영 책임을 짐 |
| CSAP와 보안 검증 | 공공기관이 사용할 서비스의 보안 수준을 사전에 심사하고 적합성을 판단하는 장치임 |
| 계약과 SLA | 가용성, 장애 대응 시간, 백업, 책임 범위를 문서화해 운영 기준으로 삼음 |
| 데이터 보호와 종료 계획 | 데이터 위치, 암호화, 반출, 종료 시 이전 절차를 정해 종속 위험을 줄이는 장치임 |

```text
| 도입 필요성 검토   | --> | 보안 요건·데이터 분류 | --> | CSAP 적합 서비스 선정 |
+----------------+     +------------------+     +------------------+
                                                        |
                                                        v
+----------------+     +------------------+     +------------------+
| 운영·점검·감사    | <-- | 계약·SLA 체결       | <-- | 전환·구축 계획 수립   |
+----------------+     +------------------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +----------------+     +----------------+
| 대상 시스템 선정 | --> | 보안 요건 확인     | --> | 인증 서비스 계약   | --> | 운영·감사·전환 점검 |
+-------------+     +----------------+     +----------------+     +----------------+
```

1. **대상 시스템 선정**: 전환 대상 업무와 시스템 중요도, 데이터 민감도를 먼저 정리함
2. **보안 요건 확인**: 공공 이용 기준과 보안 요구사항을 검토하고 필요한 인증 수준을 판단함
3. **인증 서비스 계약**: 적합한 CSP와 SLA, 책임 범위, 장애 대응, 종료 절차를 계약에 반영함
4. **운영과 점검**: 서비스 운영 중 가용성, 보안 사고, 데이터 이전 가능성을 계속 점검함

## Ⅵ. 실무 적용 및 유의점

1. 공공기관 업무시스템을 민간 클라우드로 전환할 때는 데이터 중요도와 보안 요건을 먼저 분류하지 않으면 서비스 선택이 뒤집히기 쉬우므로 CSAP 적합성 검토와 종료 계획을 계약 전에 확정하고 전환 일정 준수율과 보안 점검 지적 건수로 확인함
2. SaaS를 빠르게 도입하는 조직에서는 초기 구축은 쉬워도 데이터 반출과 장애 책임이 모호해질 수 있으므로 SLA에 백업, 복구, 반출 절차를 명확히 넣고 가용성 달성률과 반출 테스트 성공 여부로 확인함

## Ⅶ. 결론

클라우드컴퓨팅법은 도입 촉진만이 아니라 공공 이용의 보안 검증과 운영 책임을 함께 다루므로 기관은 전환 판단, 인증 검토, 종료 계획을 한 흐름으로 관리해야 함.
