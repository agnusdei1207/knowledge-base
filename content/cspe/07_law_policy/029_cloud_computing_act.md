# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 클라우드컴퓨팅법(클라우드컴퓨팅 발전 및 이용자 보호에 관한 법률)은 클라우드 산업 발전과 이용자 보호를 규정하며, 공공기관 클라우드 이용 시 **CSAP(클라우드 보안 인증)** 취득을 요구하는 **클라우드 기본법**이다.
- **왜 필요한가**: 공공기관 데이터는 민감도가 높아, 보안이 검증되지 않은 클라우드 서비스를 이용하면 대규모 유출·마비 사고의 파급력이 크다. 사전 보안 인증으로 위험을 걸러내야 한다.
- **핵심 직관**: 국가 문서를 보관하는 창고를 아무 업체나 운영하게 하지 않고, 정부가 보안을 인증한 창고 업체만 이용하도록 제한하는 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 클라우드컴퓨팅법 (상위 키워드) | 클라우드 발전·이용자 보호 기본법 | 창고업 기본법 |
| CSAP (Cloud Security Assurance Program) | 공공기관용 클라우드 보안 인증 제도 | 정부 인증 창고 마크 |
| 클라우드 우선 검토 원칙 | 공공기관이 정보시스템 구축 시 클라우드를 우선 검토하는 원칙 | 임대 우선 검토 원칙 |
| IaaS/SaaS | 인프라/소프트웨어 서비스 유형 | 빈 창고 임대 / 가구 포함 창고 임대 |
| 데이터 소재지 | 클라우드 데이터가 물리적으로 저장되는 위치(리전) | 창고 소재지 |
| 물리적 망분리 | 공공망과 인터넷망을 물리적으로 분리하는 보안 기준 | 일반 창고와 국가 창고의 물리적 분리 |
| ISMS-P | 한국 정보보호 관리체계 인증(CSAP과 별도 제도) | 건물 소방 인증(CSAP은 특수 창고 인증) |
| CSP (Cloud Service Provider) | 클라우드 서비스 제공 사업자 | 창고 운영 업체 |

## 깊이 이해
- **배경·문제의식**: 2010년대 후반부터 민간 클라우드 시장이 급성장했으나, 공공부문은 보안 우려로 온프레미스(자체 구축) 방식에 머물렀다. 이에 정부는 ① 클라우드 우선 검토 원칙을 도입해 공공 클라우드 전환을 촉진하되, ② CSAP 인증으로 보안 수준을 사전 검증하는 이중 전략을 채택했다.
- **작동 원리**:
  - **클라우드 우선 검토**: 공공기관이 정보시스템을 신규 구축·전환할 때 클라우드 이용을 우선 검토해야 한다(의무는 아니지만 우선 검토 원칙).
  - **CSAP 인증**: 공공기관이 실제로 클라우드를 이용하려면 CSAP 인증을 받은 서비스를 선택해야 한다. CSAP은 물리적 망분리·데이터 소재지·접근통제·암호화·침해사고 대응 등 보안 통제 항목을 심사한다.
  - **인증 등급**: CSAP은 데이터 민감도에 따라 등급을 나눠 심사 기준을 차등 적용한다(상·중·하 또는 기밀성 등급 기반 — 세부 등급 명칭은 고시 개정에 따라 변동 가능).
- **비유**: 공공기관이 사용하는 클라우드는 일반 은행이 아니라, 정부가 금고 안전성을 심사해 인증한 특수 금고 업체를 이용하는 것이다. 금고 등급(민감도)에 따라 심사 기준이 달라진다.
- **구체 예시**: 공공기관이 민원 시스템을 클라우드로 전환할 때, CSAP 인증을 받은 국내 리전 IaaS(예: NHN 클라우드·NCP)를 우선 검토한다. 기밀 데이터는 상위 등급 인증 서비스만 이용 가능하다.
- **흔한 오해·주의점**: ① CSAP 인증 등급·심사기준·국외 리전 허용 범위는 고시 개정에 따라 계속 변화한다 — 시험에서는 등급 세부 명칭보다 '인증을 통한 사전 검증'이라는 취지 중심으로 서술하는 것이 안전하다. ② CSAP은 공공기관용 클라우드 인증이고, ISMS-P는 일반 정보보호 관리체계 인증이다 — 적용 대상과 심사 항목이 다르다.

## 연결 개념
- **전자서명법 (028)**: 사설인증사업자가 클라우드 기반 서비스를 운영할 때 CSAP 인증 필요성
- **정보통신망법 (026)**: 클라우드 서비스 제공자(CSP)도 정보통신망법의 보호조치 의무를 지님
- **ISMS-P (031 관련)**: CSAP과 유사하지만 적용 대상·심사 항목이 다른 별도 인증

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 클라우드컴퓨팅법은 공공기관 클라우드 이용 시 CSAP 인증 서비스 선택을 요구하는 클라우드 기본법임.
> 2. **가치**: 클라우드 우선 검토 원칙으로 공공 전환을 촉진하되, CSAP 사전 인증으로 보안 수준을 검증하는 이중 전략임.
> 3. **판단 포인트**: CSAP 등급·심사기준은 고시 개정에 따라 변동하므로, 인증 취지와 구조 중심으로 서술하는 것이 안전함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 법 취지·구조 | 클라우드 우선 검토 + CSAP 사전 인증 이중 전략 | "클라우드를 쓰면 된다" 수준 서술 |
| CSAP 인증 체계 | 심사 항목(망분리·소재지·암호화 등), 등급 차등 | 등급 세부 명칭만 나열하고 취지 누락 |
| 관련 인증 구분 | CSAP vs ISMS-P 적용 대상·심사 차이 | 두 인증을 동일시 |

> 요약: 클라우드 우선 검토와 CSAP 인증의 이중 전략을 보이고, ISMS-P와 구분해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 클라우드 산업 발전·이용자 보호를 규정하며, 공공기관 클라우드 이용 시 CSAP 인증을 요구하는 기본법임
- 배경: 공공부문 클라우드 전환 수요 증가, 보안 미검증 서비스 이용 시 대규모 유출·마비 위험
- 필요성: 클라우드 우선 검토로 전환을 촉진하되, CSAP으로 보안을 사전 검증하는 이중 전략이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
클라우드컴퓨팅법 -> 클라우드 우선 검토 원칙(공공기관)
  -> CSAP 인증 체계(등급별 심사)
  -> CSP가 인증 신청 -> 심사(망분리/소재지/암호화/침해대응)
  -> 인증 취득 -> 공공기관이 인증 서비스 선택·이용
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 클라우드 우선 검토 | 공공기관 정보시스템 신규·전환 시 클라우드 우선 검토 | 의무는 아니나 원칙적 우선 검토 |
| CSAP 인증 | 공공기관용 클라우드 보안 인증 | 데이터 민감도별 등급 차등 심사 |
| 심사 항목 | 물리적 망분리·데이터 소재지·접근통제·암호화·침해 대응 | 고시 개정에 따라 변동 가능 |
| CSP | 클라우드 서비스 제공 사업자 | 인증 신청·유지 주체 |

> 요약: 우선 검토 원칙으로 전환을 촉진하고, CSAP 인증으로 보안을 사전 검증하는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
공공기관 정보시스템 신규·전환 계획
  -> 클라우드 우선 검토 -> CSP 선택(CSAP 인증 필수)
  -> CSAP 심사(망분리/소재지/암호화/침해대응)
  -> 인증 등급 확인 -> 데이터 민감도 매칭 -> 서비스 이용·모니터링
```

1. 우선 검토: 공공기관이 정보시스템 신규 구축·전환 시 클라우드 이용을 우선 검토함
2. CSAP 인증 확인: CSAP 인증을 받은 CSP 중 데이터 민감도에 맞는 등급의 서비스를 선택함
3. 심사·인증: CSP가 물리적 망분리·데이터 소재지·접근통제·암호화·침해 대응 등 항목을 심사받아 인증을 취득·유지함
4. 이용·모니터링: 공공기관이 인증 서비스를 이용하고, 인증 유효기간·갱신 여부를 주기적으로 확인함

> 요약: 우선 검토 → CSAP 인증 확인 → 등급 매칭 → 서비스 이용·모니터링의 순서로 운영됨.

---

## Ⅳ. 특징
- 이중 전략: 클라우드 전환 촉진(우선 검토)과 보안 사전 검증(CSAP)을 동시에 추구함
- 등급 차등: 데이터 민감도에 따라 심사 기준을 차등 적용해 과도한 보안 비용을 방지함
- 고시 변동성: 인증 등급·심사기준·국외 리전 허용 범위가 고시 개정에 따라 변동하므로 정책 추적이 필요함
- ISMS-P와 별도: CSAP은 공공기관용 클라우드 인증, ISMS-P는 일반 정보보호 관리체계 인증으로 적용 대상이 다름

> 요약: 이중 전략과 등급 차등이 핵심이나, 고시 변동성에 따른 정책 추적과 ISMS-P 구분이 중요함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | CSAP | ISMS-P | 선택 기준 |
|:---|:---|:---|:---|
| 적용 대상 | 공공기관용 클라우드 서비스 | 일반 정보보호·개인정보 관리체계 | 공공 클라우드 여부 |
| 심사 항목 | 망분리·데이터 소재지·클라우드 보안 특화 | 정보보호·개인정보 관리 전반 | 클라우드 특화 vs 범용 |
| 의무 대상 | 공공기관 이용 CSP | 매출·이용자 기준 의무대상 사업자 | 법적 의무 해당 여부 |

> 요약: 공공 클라우드는 CSAP, 일반 정보보호·개인정보 관리는 ISMS-P를 기준으로 적용함.

**리스크·대응:**
- 고시 변동 대응 지연: CSAP 등급·기준 변경을 추적하지 못해 인증 미갱신 → 고시 변경 모니터링 체계 수립 (지표: 고시 변경 반영 소요기간)
- 국외 리전 정책 불확실: 국외 리전 이용 허용 범위가 유동적 → 데이터 소재지 정책을 인증 취득 전 확인 (지표: 데이터 소재지 정합성)
- CSAP-ISMS 중복 부담: 두 인증의 심사 항목 중복으로 CSP 부담 → 심사 항목 상호인정·통합심사 추진 (지표: 중복 심사 항목 비율)

**점검 지표:**
- 인증 유지: CSAP 인증 유효기간 내 갱신 여부 — 인증 이력 관리
- 서비스 적합성: 데이터 민감도와 CSAP 등급 매칭 적절성 — 데이터 분류 대비 인증 등급 대조

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 민감도 분류: 공공기관 데이터를 민감도별로 분류하고, CSAP 인증 등급과 매칭해 적합한 CSP를 선택함
2. 고시 변경 모니터링: CSAP 등급·심사기준·국외 리전 정책 변경을 주기적으로 모니터링하고 내부 지침에 반영함
3. ISMS-P 연계 관리: CSAP과 ISMS-P의 중복 심사 항목을 식별해 통합 관리하고, 상호인정 추이를 추적함

**결론:**
- 기술사 판단: 공공 클라우드 전환은 CSAP 인증 서비스를 우선 선택하되, 데이터 민감도와 인증 등급의 매칭이 핵심임
- 향후 방향: SaaS 영역 CSAP 확대, 멀티 클라우드·하이브리드 환경 인증 기준 마련, ISMS-P 상호인정 체계 정비가 필요함
