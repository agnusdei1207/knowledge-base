# 📖 【암기용】 개념 완전 이해

> 목적: ISO 27701을 처음 봐도 이 표준이 27001을 대체하지 않고 그 위에 얹는 확장이라는 점을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 이미 구축된(또는 동시 구축하는) ISO 27001 ISMS 위에 개인정보 처리 관련 요구사항을 추가하는 개인정보 경영 시스템(PIMS) 확장 표준
- **왜 필요한가**: 정보 보안 통제만으로는 목적 제한, 동의 관리, 정보주체 권리 대응 같은 개인정보 특유의 요구를 다루지 못한다.
- **핵심 직관**: 기존 건물(27001 ISMS)에 개인정보 보호 전용 증축 동을 올리는 구조이지, 별도의 새 건물을 짓는 것이 아니다.

## 깊이 이해
- **배경·문제의식**:
  - 보안 사고 방지(기밀성·무결성·가용성)와 개인정보 오남용 방지(목적 제한·최소 수집·정보주체 권리)는 다른 축의 문제다.
  - 개인정보 처리자는 컨트롤러(PII controller)와 프로세서(PII processor) 역할에 따라 책임 범위가 다르다.
  - ISO 27701은 이 역할별 책임을 27001 관리 체계 위에 추가 요구사항(부속서 통제)으로 명시한다.
- **작동 원리**:
  - 조직은 먼저 ISO 27001 ISMS를 갖추거나 동시에 구축한다.
  - PII 컨트롤러·프로세서 역할을 결정하고 역할별 추가 통제(동의 관리, 목적 제한, 정보주체 권리 대응, 하위 처리자 관리)를 적용한다.
  - 기존 27001의 위험 평가·SoA 절차에 개인정보 위험 항목을 통합해 확장한다.
  - 인증심사도 27001 인증을 전제로 27701 요구사항이 추가 심사된다.
- **비유**:
  - 자동차 안전 인증(27001)에 어린이 보호 장치 인증(27701)을 추가로 받는 구조와 비슷하다. 기본 차체 인증이 없으면 추가 인증도 성립하지 않는다.
- **구체 예시**:
  - 클라우드 서비스 제공사가 PII 프로세서로서 고객사(컨트롤러)의 개인정보를 처리할 때, 27701 통제에 따라 하위 위탁업체 목록과 처리 목적을 계약서에 명시한다.
  - 정보주체의 열람·정정·삭제 요청 처리 절차를 27701 요구사항에 따라 SoA에 반영한다.
- **흔한 오해·주의점**:
  - ISO 27701은 27001과 무관한 독립 인증이 아니다. 27001 인증(또는 동시 구축) 없이 27701만 단독으로 인증받을 수 없다.
  - GDPR 준수를 자동으로 보장하지 않는다. 표준 준수는 법령 준수의 참고 근거이지 법적 면책이 아니다.
  - 컨트롤러용 통제와 프로세서용 통제가 다르므로 조직의 역할을 먼저 확정해야 한다.

## 연결 개념
- ISO/IEC 27001 — 27701이 확장하는 기반 정보 보안 경영 시스템
- GDPR — 유럽 개인정보보호 법령, 27701이 준수 참고 근거로 활용되는 규정
- 개인정보보호법 — 국내 법적 요구사항과 27701 통제 매핑 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: ISO 27701 답안은 27001 확장 관계, 컨트롤러/프로세서 구분, 추가 통제, 법령 매핑을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO 27701은 ISO 27001 ISMS 위에 개인정보 처리 요구사항을 추가하는 확장 표준이다.
> 2. **가치**: 컨트롤러·프로세서 역할별 통제를 명시해 개인정보 처리 책임 범위를 문서로 구분한다.
> 3. **판단 포인트**: 27001 인증 여부와 조직의 역할(컨트롤러/프로세서)에 따라 적용 통제 범위가 달라진다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 확장 표준 관계 이해 확인 | 27001 기반 위에 27701 요구사항 추가 | 27701을 27001과 무관한 독립 인증으로 서술 |
| 역할별 통제 이해 확인 | PII 컨트롤러·프로세서 구분 통제 | 두 역할 통제를 구분 없이 나열 |
| 법령 연계 이해 확인 | GDPR·개인정보보호법과 통제 매핑 | 표준 인증이 법적 면책이라고 서술 |

> 요약: 이 문제는 27701 통제 목록보다 27001과의 확장 관계와 역할 구분을 먼저 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: ISO 27001 위에 개인정보 처리 요구사항을 추가하는 PIMS 확장 표준
- 배경: 정보 보안 통제만으로 동의 관리, 목적 제한, 정보주체 권리 대응을 다루지 못함
- 필요성: 컨트롤러·프로세서 역할 구분, 하위 처리자 관리, 정보주체 권리 대응 절차 마련이 필요
---
## Ⅱ. 구조 및 구성요소

```text
ISO 27001 ISMS(기반) -> PII Role Determination(Controller/Processor)
  -> Additional PIMS Control -> Consent/Purpose Limitation
  -> Data Subject Rights Process -> SoA Extension
  -> Certification Audit(27001 + 27701)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 27001 ISMS 기반 | 27701 통제가 얹히는 전제 경영 체계 | 27001 없이 27701 단독 인증 불가 |
| PII 역할 구분 | 컨트롤러·프로세서 책임 범위 결정 | 역할별 통제 항목 상이 |
| 동의·목적 제한 통제 | 수집 목적 명시, 동의 획득·철회 절차 | 목적 외 이용 금지 근거 문서화 |
| 정보주체 권리 대응 | 열람·정정·삭제 요청 처리 절차 | 처리 기한, 절차 문서 필요 |
| 하위 처리자 관리 | 위탁업체 개인정보 처리 통제 | 계약서 상 처리 범위 명시 |

> 요약: ISO 27701은 27001 기반 위에 역할 구분과 정보주체 권리 대응 통제를 추가한 구조다.
---
## Ⅲ. 동작원리 및 흐름도

```text
27001 ISMS Confirm -> PII Role Decide(Controller/Processor)
  -> Additional Control Select -> Consent/Purpose Document
  -> Data Subject Request Handle -> SoA Update
  -> Internal Audit -> 27001+27701 Certification Audit
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 27001 ISMS 구축 여부 확인 또는 동시 구축 | 27001 인증서·SoA 존재 여부 |
| 2 | 조직의 PII 컨트롤러·프로세서 역할 결정 | 계약서, 처리 위탁 구조 |
| 3 | 동의·목적 제한·하위 처리자 통제 적용 | 동의 기록, 위탁 계약 조항 |
| 4 | 정보주체 권리 요청 처리 절차 운영 | 요청 처리 기한 준수율 |
| 5 | 27001 통합 심사로 27701 요구사항 검증 | 부적합 사항, 인증서 발급 여부 |

> 요약: 27701 운영은 27001 기반 확인부터 역할 결정, 통제 적용, 통합 심사까지 이어진다.
---
## Ⅳ. 특징

| 구분 | ISO 27001(기반) | ISO 27701(확장) | 수치·표준 관련 포인트 |
|:---|:---|:---|:---|
| 대상 | 정보 자산 전반 위험 | 개인정보(PII) 처리 활동 | 27001 위에 추가 요구사항 |
| 단독 인증 | 단독 인증 가능 | 27001 없이 단독 인증 불가 | 27001+27701 결합 인증서 발급 |
| 핵심 통제 | Annex A 조직·인적·물리적·기술적 통제 | 동의, 목적 제한, 정보주체 권리 | 컨트롤러·프로세서 역할별 통제 |
| 법령 연계 | 보안 법령 일반 참고 | GDPR·개인정보보호법 매핑 근거 | 국가별 법령 요구사항과 통제 대조표 활용 |

> 요약: 27701은 27001을 전제로 개인정보 특유 통제를 추가한다는 점이 가장 큰 차이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | ISO 27001 단독 적용 | ISO 27701 확장 적용 | 선택 기준 |
|:---|:---|:---|:---|
| 적용 범위 | 정보 자산 보안 전반 | 개인정보 처리 활동 추가 커버 | PII 처리 비중이 크면 27701 확장 |
| 법적 대응 | 보안 법령 일반 대응 | GDPR·개인정보보호법 요구사항 매핑 | 해외 고객 데이터 처리 시 27701 우선 |
| 인증 관계 | 독립 인증 가능 | 27001 기반 필수, 단독 불가 | 27701만 검토 중이면 27001 선행 확인 |

> 요약: PII 처리 비중과 해외 법령 대응 필요성이 클수록 27701 확장 적용을 우선한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 27001 미비 상태 확장 시도 | 기반 ISMS 없이 27701 요구사항만 도입 | 27001 인증·SoA 선확보 후 확장 | 27001 인증서 유효 여부 |
| 역할 혼동 | 컨트롤러·프로세서 통제 미구분 | 계약서 기반 역할 명확화 | 역할별 통제 매핑표 |
| 법령 갱신 미반영 | GDPR·개인정보보호법 개정 미추적 | 법령 변경 모니터링 절차 수립 | 법령 대조표 갱신 이력 |

> 요약: 27701 운영 리스크는 27001 기반 미비와 역할 혼동에서 시작된다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 기반 인증 | 27001 인증 유효 상태 유지 | 인증서, 사후관리심사 결과 |
| 정보주체 대응 | 권리 요청 처리 기한 준수율 100% | 요청 처리 이력 대장 |
| 하위 처리자 관리 | 위탁 계약 개인정보 조항 반영률 100% | 계약서 점검, 위탁사 심사 |

> 요약: 도입 성공 여부는 27001 기반 유지, 정보주체 대응 기한 준수, 위탁 계약 반영률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. ISO 27001 ISMS 구축 상태를 먼저 확인하고 미구축 시 27701과 동시 구축 계획을 수립함
2. 조직의 PII 컨트롤러·프로세서 역할을 계약서 기준으로 결정하고 역할별 통제를 SoA에 반영함
3. 정보주체 권리 요청 처리 절차와 하위 처리자 관리 체계를 문서화하고 처리 기한을 지표로 관리함

**결론 (2줄):**
- 기술사 판단: ISO 27701은 27001을 대체하지 않고 그 위에 개인정보 통제를 추가하는 확장 표준으로 접근해야 함
- 향후 방향: GDPR, 국내 개인정보보호법 개정 사항을 지속 반영해 통제 매핑표를 최신화해야 함
