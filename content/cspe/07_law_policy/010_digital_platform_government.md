## 미리 알고가기

- 디지털 플랫폼 정부: 정부 데이터와 서비스를 플랫폼 형태로 연결해 국민, 기업, 정부가 함께 활용하는 행정 모델임
- Once Only: 국민이 이미 제출한 정보를 행정기관 간 연계로 재제출하지 않게 하는 원칙임
- API 개방: 공공 데이터와 기능을 표준 인터페이스로 외부 서비스와 연결하는 방식임
- 마이데이터: 정보주체가 본인 데이터를 통제하고 필요한 서비스에 활용하게 하는 체계임
- GovTech: 민간 기술 기업이 공공서비스 문제 해결에 참여하는 영역임

## Ⅰ. 개요

- **정의/개념**: 디지털 플랫폼 정부는 공공 데이터, 행정 서비스, 민간 서비스를 플랫폼과 API로 연결해 맞춤형 행정과 민간 참여 서비스를 제공하는 정부 운영 모델임
- **배경/필요성**: 부처별 시스템과 서류 중심 절차는 국민에게 반복 제출과 복수 창구 이용을 요구하므로, 데이터 연계와 서비스 통합 기준이 필요함

## Ⅱ. 특징

- 부처별 시스템보다 데이터 연계와 공통 플랫폼을 중심으로 서비스를 설계함
- 국민이 여러 기관을 따로 방문하지 않도록 선제 안내와 통합 접점을 제공함
- 공공은 데이터, 인증, 표준을 제공하고 민간은 부가서비스를 구현함
- 개인정보 보호와 데이터 품질 관리가 약하면 연계 서비스 신뢰가 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전자정부 | 디지털 플랫폼 정부 |
|:---|:---|:---|
| 서비스 구조 | 부처별 온라인 서비스 제공 | 공통 플랫폼과 API 기반 서비스 연결 |
| 데이터 활용 | 기관 내부 데이터 중심 | 기관 간 데이터 연계와 민간 활용 확대 |
| 국민 경험 | 서비스별 방문과 신청 중심 | 통합 접점, 선제 안내, 반복 제출 감소 |
| 민간 참여 | 위탁 개발과 제한적 연계 | GovTech, SaaS, API 기반 참여 |

> 요약: 디지털 플랫폼 정부는 행정 전산화가 아니라 데이터와 서비스 연결 방식을 바꾸는 모델임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 공공 데이터 기반 | 기관별 데이터를 표준화하고 품질을 관리함 |
| API·연계 플랫폼 | 데이터와 행정 기능을 표준 인터페이스로 연결함 |
| 디지털 신원·인증 | 사용자의 신원 확인과 권한 관리를 수행함 |
| 민간 참여 체계 | 민간 서비스가 공공 데이터와 기능을 활용할 수 있게 함 |
| 보안·개인정보 통제 | 접근 권한, 이용 기록, 목적 외 이용을 관리함 |

```text
+-----------+     +-----------+     +-----------+
| 공공 데이터 | --> | 플랫폼/API | --> | 국민/민간 서비스 |
+-----------+     +-----------+     +-----------+
       |               |
       v               v
   품질 관리       인증/보안 통제
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +--------------+
| 데이터 표준화 | --> | API/플랫폼 구축 | --> | 서비스 연계   | --> | 이용/성과 관리 |
+-------------+     +-------------+     +-------------+     +--------------+
```

1. **데이터 표준화**: 기관별 데이터 형식, 품질, 메타데이터를 정비함
2. **API/플랫폼 구축**: 공통 인증, 연계, 권한 관리 기능을 마련함
3. **서비스 연계**: 행정 서비스와 민간 서비스를 통합 접점으로 연결함
4. **이용/성과 관리**: 이용률, 재제출 감소, 민원 처리 시간을 측정함

## Ⅵ. 실무 적용 및 유의점

1. 복지·민원 서비스에서는 데이터 품질이 낮으면 맞춤 안내가 틀릴 수 있으므로 원천 데이터 정합성을 먼저 점검하고 오류 정정 건수와 재제출 감소율로 확인함
2. 민간 API 연계를 확대할 때 개인정보 목적 외 이용 위험이 커지므로 동의, 접근권한, 이용기록 관리를 설계하고 접근 위반 건수와 API 장애율로 확인함

## Ⅶ. 결론

디지털 플랫폼 정부는 부처별 서비스를 하나로 포장하는 사업이 아니라 데이터 표준, API 연계, 보안 통제를 통해 행정 서비스 제공 절차를 바꾸는 모델임

## 작성 근거(검토용)

- DPG 문맥에서는 `혁신`, `신패러다임`보다 데이터 연계, API, 통합 접점, 개인정보 통제가 정확한 판단어임
- 전자정부와의 차이를 서비스 구조와 데이터 활용으로 좁혀 단순 온라인화와 구분함
- 민간 참여는 무조건 긍정이 아니므로 개인정보와 API 장애를 실무 유의점에 함께 배치함
