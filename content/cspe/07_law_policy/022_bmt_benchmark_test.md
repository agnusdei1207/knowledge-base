# 📖 【암기용】 개념 완전 이해

> 목적: BMT를 처음 봐도 왜 도입 전에 성능을 직접 측정해야 하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 정보화 사업에서 제품·시스템을 실제 도입하기 전 요구사항 기준으로 성능·기능·안정성을 검증하는 절차
- **왜 필요한가**: 카탈로그 스펙과 실제 운영 환경 성능은 다를 수 있어, 도입 후 SLA 미달·재구축 위험을 사전에 걸러내야 한다
- **핵심 직관**: 자동차를 사기 전 시승을 통해 카탈로그 연비와 실제 주행 성능 차이를 확인하는 절차다

## 깊이 이해
- **배경·문제의식**: 제안서 스펙만으로 제품을 선정하면 실사용 환경에서 TPS(초당 트랜잭션) 미달, 장애 빈발 문제가 뒤늦게 드러난다
- **작동 원리**: 실제 업무 시나리오와 유사한 부하를 인가해 응답시간, 처리량, 장애 복구 시간을 측정하고 요구사항 기준과 비교한다
- **비유**: 신입사원 채용 시 이력서(스펙)만 보지 않고 실무 과제(BMT)를 시켜 실제 역량을 확인하는 방식이다
- **구체 예시**: BMT 계획서에 목표 TPS 1,000, 응답시간 200ms 이내를 명시하고, 부하테스트 도구로 동시 사용자 500명 시나리오를 재현해 결과를 측정한다
- **흔한 오해·주의점**: BMT 통과가 운영 환경 전체 안정성을 보장하지 않는다는 점이다
- **흔한 오해·주의점 2**: 테스트 환경과 운영 환경의 하드웨어·네트워크 조건이 다르면 측정치가 왜곡될 수 있다

## 연결 개념
- SW 기술성 평가 — 기술 역량 심사와 함께 진행되는 정량 검증 절차
- SLA(Service Level Agreement) — BMT 목표 지표가 계약 SLA로 이어짐
- 성능테스트·부하테스트 — BMT의 세부 실행 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: BMT 답안은 계획서 설계, 측정 지표, 평가위원회 운영, 결과 검증 절차를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: BMT는 도입 전 제품·시스템 성능을 실제 부하 조건에서 정량 측정해 요구사항 충족 여부를 검증하는 절차이다.
> 2. **가치**: 카탈로그 스펙과 실사용 성능 간 괴리를 사전에 걸러내 재구축·SLA 미달 위험을 줄인다.
> 3. **판단 포인트**: 측정 시나리오의 운영 환경 재현도와 목표 지표(TPS, 응답시간, 가용성) 설정이 신뢰도를 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| BMT 절차 이해 확인 | 계획서, 시나리오 설계, 측정, 평가위원회 | 절차 없이 "성능을 테스트한다" 수준 서술 |
| 정량 지표 이해 확인 | TPS, 응답시간, 가용성, 오류율 | 지표 없이 "빠르다/안정적이다" 서술 |
| 신뢰성 확보 방안 확인 | 운영 환경 재현, 반복 측정, 제3자 검증 | 1회성 측정만 언급하고 재현성 누락 |

> 요약: 이 문제는 테스트 도구 나열보다 시나리오 설계와 결과 신뢰성 확보 절차를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 도입 전 제품·시스템 성능을 실제 부하로 정량 검증하는 절차
- 배경: 제안서 스펙과 실사용 성능 간 괴리로 도입 후 SLA 미달 사례 발생
- 필요성: 목표 TPS·응답시간·가용성을 사전 검증해 재구축·장애 위험 최소화

---

## Ⅱ. 구조 및 구성요소

```text
요구사항 정의 -> BMT 계획서 작성
  -> 시나리오·부하 설계 -> 측정 도구 구성
  -> 테스트 실행 -> 평가위원회 검토 -> 결과 보고서
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| BMT 계획서 | 목표 지표·시나리오·일정 정의 | 목표 TPS, 응답시간, 가용성 명시 |
| 부하 시나리오 | 실사용 패턴 재현 | 동시 사용자 수, 트랜잭션 비율 |
| 측정 도구 | 부하 발생·지표 수집 | 응답시간, 처리량, 오류율 로깅 |
| 평가위원회 | 결과 적합성 심사 | 발주기관·제3자·전문가 참여 |

> 요약: BMT는 계획서, 부하 시나리오, 측정 도구, 평가위원회를 통해 도입 전 성능을 검증한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 확정 -> 목표 지표 설정 -> 시나리오 부하 인가
  -> 지표 측정 -> 기준 대비 판정 -> 평가위원회 승인 -> 도입 결정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표 TPS·응답시간·가용성 확정 | 요구사항 명세서 부합 여부 |
| 2 | 운영 유사 환경에서 부하 인가 | 하드웨어·네트워크 조건 재현도 |
| 3 | 처리량·응답시간·오류율 측정 | 목표 기준 대비 충족 여부 |
| 4 | 평가위원회가 결과 적합성 판정 | 반복 측정 일관성, 이상치 확인 |

> 요약: BMT는 목표 지표 설정, 부하 인가, 측정, 위원회 판정 순으로 도입 여부를 결정한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 실사용 조건에서 성능 사전 검증 | 재구축 위험, SLA 미달 위험 감소 |
| 한계 | 테스트 환경과 운영 환경 차이 존재 | 하드웨어·네트워크 조건 재현 한계 |
| 비교 포인트 | 카탈로그 스펙 검토 대비 신뢰도 차이 | 측정 데이터 기반 vs 서류 기반 판단 |

> 요약: BMT는 실측 기반 신뢰도가 높지만 환경 재현 한계로 결과 해석에 주의가 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 서류 심사(스펙 검토) | BMT | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 제안서 기재 수치 확인 | 실측 부하 테스트 | 핵심 업무 시스템은 BMT 필수 |
| 비용/성능 | 검증 비용 낮음, 신뢰도 낮음 | 검증 비용 증가, 신뢰도 향상 | 장애 영향도가 큰 사업일수록 BMT 강화 |
| 운영/위험 | 실사용 성능 미확인 위험 | 환경 재현 오차 위험 | 운영 환경과 유사한 테스트베드 구축 |

> 요약: 장애 영향이 큰 핵심 시스템일수록 서류 심사보다 BMT 실측 검증을 우선한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 환경 재현 오차 | 테스트 환경과 운영 환경 차이 | 운영 환경과 동일한 사양의 테스트베드 구성 | 하드웨어·네트워크 사양 일치율 |
| 시나리오 편향 | 특정 유리한 조건만 측정 | 발주기관이 시나리오 사전 승인 | 시나리오 요구사항 반영률 |
| 일회성 측정 | 단발 테스트로 일관성 미확인 | 반복 측정과 통계적 신뢰구간 적용 | 반복 측정 편차, 신뢰구간 |

> 요약: BMT 리스크는 환경 재현성 확보와 반복 측정 검증으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | 목표 TPS 달성 여부 | 부하테스트 도구 로그 |
| 응답성 | 목표 응답시간 이내 | APM, 트랜잭션 로그 |
| 안정성 | 장시간 부하 시 오류율 기준 이내 | 내구성 테스트, 오류 로그 분석 |

> 요약: BMT 성과는 목표 TPS·응답시간·오류율 충족 여부로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. BMT 계획서에 목표 TPS·응답시간·가용성 기준을 수치로 명시하고 발주기관이 사전 승인함
2. 운영 환경과 동일한 사양의 테스트베드를 구성해 시나리오 부하를 반복 측정함
3. 평가위원회가 반복 측정 결과의 일관성과 이상치를 검토한 뒤 도입 여부를 최종 판정함

**결론 (2줄):**
- 기술사 판단: 장애 영향도가 큰 핵심 정보화 사업은 서류 심사만으로 그치지 않고 실측 BMT를 병행해야 함
- 향후 방향: 클라우드 기반 자동화 부하테스트 도구를 활용해 BMT 반복 검증 주기를 단축하고 신뢰도를 높여야 함

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "BMT를 설명하시오" | 계획서, 시나리오, 측정 흐름 | 서류 심사와의 차이 |
| 방안 제시형 | "BMT 신뢰성 확보 방안을 제시하시오" | 환경 재현, 반복 측정 | 리스크·지표 중심 개선안 |

> 요약: 설명형은 BMT 절차, 방안형은 신뢰성 확보와 환경 재현 정확도 중심으로 답안 축을 바꾼다.
