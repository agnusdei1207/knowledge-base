## 미리 알고가기

- 디지털 접근성: 장애, 연령, 환경과 관계없이 디지털 서비스를 이용할 수 있게 하는 설계 기준임
- WCAG: 웹 콘텐츠 접근성 국제 지침으로 인식, 운용, 이해, 견고성 원칙을 제시함
- POUR: Perceivable, Operable, Understandable, Robust의 약어임
- WAI-ARIA: 보조기술이 웹 UI의 역할과 상태를 이해하도록 돕는 속성 체계임
- 대체 텍스트: 이미지의 의미를 화면낭독기가 전달할 수 있게 제공하는 텍스트임

## Ⅰ. 개요

- **정의/개념**: 디지털 접근성은 웹, 앱, 키오스크 등 디지털 서비스가 장애 유형과 이용 환경 차이에도 인식, 조작, 이해 가능하도록 설계·검증하는 기준임
- **배경/필요성**: 공공과 금융 서비스가 온라인 중심으로 이동하면 접근성 결함이 민원 처리, 결제, 정보 획득의 배제로 이어질 수 있음

## Ⅱ. 특징

- 접근성은 디자인 선택이 아니라 서비스 이용 가능 여부를 좌우하는 품질 속성임
- WCAG는 인식 가능성, 운용 가능성, 이해 가능성, 견고성의 네 원칙으로 요구사항을 분류함
- 키보드 조작, 명도 대비, 대체 텍스트, 오류 안내처럼 구현 단계의 검증 항목이 필요함
- 자동 진단만으로는 동적 UI와 실제 보조기술 사용성을 모두 확인하기 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 인식 가능성 | 운용 가능성 | 이해 가능성 | 견고성 |
|:---|:---|:---|:---|:---|
| 의미 | 콘텐츠를 감각적으로 인식할 수 있어야 함 | 키보드와 보조기술로 조작할 수 있어야 함 | 화면 흐름과 오류 안내를 이해할 수 있어야 함 | 다양한 브라우저와 보조기술에서 해석돼야 함 |
| 구현 예 | 대체 텍스트, 자막, 명도 대비 | 키보드 포커스, 충분한 입력 시간 | 일관된 내비게이션, 명확한 오류 메시지 | 표준 HTML, ARIA 역할과 상태 |
| 결함 영향 | 이미지와 영상 의미를 놓침 | 버튼, 메뉴, 폼을 사용할 수 없음 | 신청 절차와 오류 원인을 알기 어려움 | 화면낭독기와 UI 상태가 어긋남 |

> 요약: WCAG의 네 원칙은 접근성 요구를 사용자 경험이 아니라 검증 가능한 구현 조건으로 바꿔줌

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 접근성 요구사항 | 장애 유형, 이용 환경, 법·지침 기준을 요구사항으로 반영함 |
| UI 구현 기준 | 색상 대비, 포커스 순서, 키보드 조작, 오류 안내를 설계함 |
| 보조기술 호환성 | 화면낭독기, 확대, 음성 입력 같은 도구와의 동작을 확인함 |
| 테스트 체계 | 자동 진단, 수동 점검, 사용자 테스트를 함께 수행함 |
| 운영 관리 | 신규 콘텐츠와 기능 변경 시 접근성 결함을 재검토함 |

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 요구사항   | --> | UI 구현   | --> | 보조기술 검증 | --> | 운영 점검 |
+-----------+     +-----------+     +-----------+     +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +--------------+
| 기준 선정      | --> | 설계/개발 반영 | --> | 접근성 테스트 | --> | 결함 수정/재검증 |
+-------------+     +-------------+     +-------------+     +--------------+
```

1. **기준 선정**: WCAG, KWCAG, 앱·키오스크 지침 중 적용 기준을 정함
2. **설계/개발 반영**: 색상, 폼, 포커스, ARIA, 오류 안내를 구현함
3. **접근성 테스트**: 자동 도구와 수동 점검으로 결함을 찾음
4. **결함 수정/재검증**: 보조기술 환경에서 수정 결과를 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 공공 웹서비스에서는 자동 진단 통과만으로 접근성을 판단하면 동적 메뉴와 폼 오류가 남을 수 있으므로 화면낭독기와 키보드 테스트를 병행하고 수동 결함 재발률로 확인함
2. 모바일 앱과 키오스크는 터치 영역과 시간 제한 문제가 크므로 포커스 이동, 음성 안내, 입력 시간 연장을 검토하고 과업 완료율과 접근성 민원 건수로 확인함

## Ⅶ. 결론

디지털 접근성과 WCAG는 정보 평등을 선언하는 문구가 아니라 콘텐츠 인식, 조작, 이해, 보조기술 호환성을 구현하고 검증하는 품질 기준임

## 작성 근거(검토용)

- 접근성 주제에서 `보장`은 법적·품질 맥락이 섞이므로 실제 구현 기준인 인식, 운용, 이해, 견고성으로 풀어 썼음
- WCAG는 원칙 이름만 외우면 답안이 약해져 원칙별 구현 예와 결함 영향을 표에 넣음
- 자동 진단의 한계를 반영해 수동 점검과 보조기술 테스트를 실무 유의점에 배치함
