# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 디지털 접근성은 **장애인·고령자를 포함한 모든 사용자가 웹·앱 등 디지털 서비스를 동등하게 인식·이용할 수 있게 하는 설계 원칙**이며, 그 국제 표준이 W3C WAI가 제정한 **WCAG(Web Content Accessibility Guidelines) 2.1**이다. 핵심은 4대 원칙 **POUR(인식·운용·이해·견고)**와 준수 수준 **A / AA / AAA**로 웹 콘텐츠의 장벽을 제거한다는 점이다.
- **왜 필요한가**: 디지털 리터러시(013)가 사용자의 '역량'을 키운다면, 접근성은 '서비스 자체가 장벽 없게' 만드는 반대편 축이다. 시각·청각·지체·인지 장애인이 스크린리더·키보드만으로도 서비스를 쓰게 해야 하며, 국내에선 **장애인차별금지법**이 웹 접근성 준수를 법적 의무로 강제한다.
- **핵심 직관**: 접근성은 '건물의 경사로·점자블록'의 웹 버전이다. 계단만 있으면 휠체어 이용자가 못 들어오듯, 이미지에 대체텍스트가 없으면 시각장애인은 스크린리더로 내용을 못 듣는다. WCAG는 '어떤 경사로를 어떻게 놓아야 하는지'를 4원칙·성공기준으로 규정한 설계 표준이다.

## 핵심 용어 정리
답안에 등장하는 상위 키워드와 내부 용어를 먼저 이해한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 디지털 접근성 | 모든 사용자가 동등하게 이용하도록 장벽 제거 | 웹의 경사로·점자블록 |
| WCAG 2.1 | W3C WAI의 웹 콘텐츠 접근성 국제 지침 | 접근성 설계 표준서 |
| W3C WAI | 웹 접근성을 담당하는 W3C 이니셔티브 | 표준 제정 기구 |
| POUR 4원칙 | 인식·운용·이해·견고(Perceivable·Operable·Understandable·Robust) | 접근성 4기둥 |
| 인식(Perceivable) | 콘텐츠를 감각으로 인지 가능 | 대체텍스트·자막 |
| 운용(Operable) | 키보드 등으로 조작 가능 | 마우스 없이 이동 |
| 이해(Understandable) | 내용·동작이 예측 가능·명료 | 일관된 내비게이션 |
| 견고(Robust) | 보조기술과 호환·해석 가능 | 스크린리더 호환 |
| 준수 수준 A/AA/AAA | 성공기준 충족 강도(AA가 실무 기준) | 초급·표준·최상 |
| 성공기준(Success Criteria) | 원칙별 검증 가능한 판정 항목 | 채점 체크리스트 |
| 스크린리더 | 화면 내용을 음성으로 읽는 보조기술 | 시각장애인의 눈 |
| 대체텍스트(alt) | 이미지를 설명하는 텍스트 | 그림의 자막 |
| WA인증마크 | 웹 접근성 품질인증(KWCAG 기반) | 접근성 합격 도장 |
| KWCAG | 한국형 웹 콘텐츠 접근성 지침(국가표준) | 국내판 WCAG |

## 깊이 이해
- **배경·문제의식**: 초기 웹은 시각·마우스 중심으로 설계돼, 이미지·색상·마우스 조작에 의존하면 시각·지체 장애인이 배제됐다. W3C는 1999년 WCAG 1.0을 시작으로 2008년 2.0, 2018년 **2.1**(모바일·저시력·인지장애 성공기준 추가), 2023년 2.2로 확장했다. 국내는 이를 반영한 **KWCAG**를 국가표준으로 두고, 장애인차별금지법으로 준수를 의무화했다.
- **작동 원리(어떻게+왜)**: WCAG는 4원칙(POUR) 아래 검증 가능한 **성공기준**을 두고, 각 기준을 A(필수)·AA(권장·실무 표준)·AAA(최고)로 등급화한다. 예를 들어 '이미지 대체텍스트'(인식), '키보드 접근'(운용), '명도 대비 4.5:1 이상'(인식·AA), '일관된 내비게이션'(이해)이 성공기준이다. 왜 등급을 두느냐면, 모든 서비스가 AAA를 달성하긴 어려워 법·공공은 대체로 **AA**를 기준으로 삼기 때문이다.
- **비유**: 건축 배리어프리 인증과 같다. 경사로 기울기·문 폭·점자표지를 항목별로 점검해 등급을 주듯, 웹도 대체텍스트·키보드·명도대비를 성공기준으로 점검해 A/AA/AAA를 판정한다.
- **구체 예시**: 시각장애인은 스크린리더로 웹을 듣는데, 이미지에 alt가 없으면 '이미지'로만 읽혀 내용을 알 수 없다. 지체장애인은 마우스 대신 키보드 Tab으로 이동하므로 모든 기능이 키보드로 조작돼야 한다. 저시력자는 명도 대비 4.5:1(AA) 이상이어야 텍스트를 읽는다. 국내 공공·민간 사이트는 **WA(웹 접근성) 품질인증**을 받아 준수를 입증한다.
- **흔한 오해·주의점**: ① **접근성 ≠ 장애인 전용** — 자막·명확한 UI는 고령자·일시적 부상자·소음 환경 사용자 등 모두에게 이롭다(보편적 설계). ② **디자인 훼손이 아니다** — 대체텍스트·시맨틱 마크업은 시각 디자인과 무관하게 병행 가능하다. ③ **AAA가 항상 목표가 아니다** — AAA는 일부 콘텐츠에 비현실적이라 법·공공 기준은 **AA**다.

## 연결 개념
- 디지털 리터러시 (013 참조): 사용자 '역량'을 키우는 축과, 서비스 '장벽 제거'를 하는 접근성 축이 함께 디지털 포용을 완성
- 장애인차별금지법: 웹 접근성 준수를 법적 의무로 강제하는 국내 근거
- 지능정보화기본법 (023 참조): 정보접근성 보장·정보격차 해소의 상위 법적 틀

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 디지털 접근성은 모두가 서비스를 동등하게 이용하게 하는 설계 원칙이며, WCAG 2.1이 POUR 4원칙·A/AA/AAA로 규정한 국제 표준임.
> 2. **가치**: 대체텍스트·키보드 접근·명도 대비 등 성공기준으로 장애인·고령자의 웹 배제를 제거하고, 보편적 설계로 전체 사용자에 이로움.
> 3. **판단 포인트**: AAA는 비현실적이라 법·공공은 AA를 기준으로 하며, 국내는 장애인차별금지법으로 준수가 법적 의무임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 원칙 구조 이해 | POUR 4원칙과 성공기준 체계 | 4원칙 명칭 누락 또는 혼동 |
| 준수 수준 이해 | A/AA/AAA와 실무 기준 AA | 무조건 AAA 목표로 단정 |
| 법·제도 이해 | 장애인차별금지법 의무·WA 인증 | 법적 의무 아닌 권고로 단정 |

> 요약: POUR 4원칙과 성공기준, 실무 기준 AA, 장애인차별금지법 의무를 함께 짚고 접근성을 장애인 전용으로 협소화하지 말아야 함.

## Ⅰ. 개요 및 필요성

- 개요: 디지털 접근성은 장애인·고령자 포함 모두가 디지털 서비스를 동등 이용하게 하는 설계 원칙임
- 배경: 시각·마우스 중심 웹 설계가 장애인을 배제해 W3C가 WCAG로 표준을 제정함
- 필요성: 대체텍스트·키보드·명도 대비 등으로 감각·조작 장벽을 제거할 필요
- 법적 요구: 장애인차별금지법이 웹 접근성 준수를 의무화해 법적 이행이 필요

---

## Ⅱ. 구조 및 구성요소

```text
[WCAG 2.1 = 웹 콘텐츠 접근성 지침]
      |
   POUR 4원칙
      |
   +-- 인식(Perceivable): 대체텍스트 / 자막 / 명도대비 4.5:1(AA)
   +-- 운용(Operable): 키보드 접근 / 충분한 시간 / 발작 유발 금지
   +-- 이해(Understandable): 가독성 / 예측 가능 / 입력 오류 안내
   +-- 견고(Robust): 보조기술·마크업 호환
      |
   각 원칙 -> 성공기준 -> 준수 수준 A / AA(실무 기준) / AAA
      |
   [KWCAG 국가표준] -> [WA 품질인증] -> [장애인차별금지법 의무]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 인식(Perceivable) | 감각으로 콘텐츠 인지 보장 | 대체텍스트·자막·명도대비 |
| 운용(Operable) | 키보드 등 조작 가능 보장 | 마우스 비의존 |
| 이해(Understandable) | 내용·동작 명료·예측 가능 | 일관 내비게이션 |
| 견고(Robust) | 보조기술 호환 보장 | 시맨틱 마크업 |
| 준수 수준 | A/AA/AAA 강도 판정 | 실무·법 기준은 AA |

> 요약: WCAG 2.1은 POUR 4원칙 아래 성공기준을 두고 A/AA/AAA로 등급화하며, 국내는 KWCAG·WA인증·차별금지법으로 이행함.

## Ⅲ. 동작원리 및 흐름도

```text
[설계 단계 접근성 반영: 시맨틱 마크업·대체텍스트]
   -> [4원칙 성공기준 점검: 인식/운용/이해/견고]
   -> [자동·수동 평가: 검사도구 + 스크린리더 실사용]
   -> [준수 수준 판정(AA) 및 개선]
   -> [WA 품질인증 획득·유지]
```

- 1단계 [설계 반영]: 개발자가 기획·설계 단계부터 시맨틱 마크업·대체텍스트·키보드 순서를 반영함
- 2단계 [기준 점검]: 평가자가 POUR 4원칙의 성공기준(명도대비·키보드·오류안내 등)을 항목별로 점검함
- 3단계 [평가]: 평가자가 자동 검사도구와 스크린리더 실사용을 병행해 실제 이용 가능성을 검증함
- 4단계 [인증·유지]: 기관이 AA 준수를 확인해 WA 품질인증을 받고, 콘텐츠 변경 시 재점검으로 유지함

> 요약: 설계 단계부터 접근성을 반영하고 4원칙 성공기준을 자동·수동으로 평가해 AA 준수를 판정·인증·유지함.

---

## Ⅳ. 특징
- 원칙 기반: 개별 기술이 아닌 POUR 4원칙과 검증 가능한 성공기준으로 규정
- 등급 체계: A/AA/AAA로 준수 강도를 구분하되 실무·법 기준은 AA
- 보편적 설계: 장애인뿐 아니라 고령자·일시 부상자·소음 환경 사용자에도 이로움
- 법적 강제성: 국내 장애인차별금지법이 준수를 의무화해 미준수 시 차별로 간주
- 기술 중립성: 특정 브라우저·기기가 아닌 보조기술 호환(견고성)을 요구

> 요약: 원칙 기반·등급 체계·보편적 설계·법적 강제성·기술 중립성이 특징으로, 설계 단계 반영이 핵심임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 준수 수준 A | 준수 수준 AA | 준수 수준 AAA |
|:---|:---|:---|:---|
| 성격 | 최소 필수 | 권장·실무 표준 | 최고 수준 |
| 대표 기준 | 대체텍스트·키보드 접근 | 명도 대비 4.5:1·자막 | 명도 대비 7:1·수어 |
| 적용 대상 | 모든 웹 최소 요건 | 공공·법적 기준선 | 특수 목적 콘텐츠 |
| 달성 난이도 | 낮음 | 중간 | 높음(일부 비현실적) |
| 판단 | 미달 시 즉시 장벽 | 목표 기준선 | 필요 콘텐츠에 선별 |

> 요약: A는 최소, AA는 공공·법 기준선, AAA는 특수 목적 선별 적용으로, 실무 목표는 AA로 설정함.

**리스크·대응(리스크 — 원인 — 대응):**
- 사후 땜질 — 완성 후 접근성 추가 — 설계·기획 단계부터 접근성 반영(Shift-Left)
- 형식 인증 — 자동검사만 통과 — 스크린리더·키보드 실사용 수동 검증 병행
- 유지 실패 — 콘텐츠 변경 후 미점검 — 배포 파이프라인에 접근성 회귀 점검 포함

**적용 판단 지표(지표 — 목표 — 측정):**
- 준수 수준 — AA 성공기준 충족 — 성공기준별 통과율·미준수 항목 수 추적
- 명도 대비 — 4.5:1 이상(AA) — 대비 검사도구 자동 측정
- 실사용성 — 스크린리더·키보드 완주 — 보조기술 실사용 태스크 성공률 측정

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 설계 단계 반영: 시맨틱 HTML·대체텍스트·키보드 포커스 순서를 기획·개발 초기부터 적용해 사후 재작업을 줄이고 AA 성공기준을 기본값으로 설정
2. 자동·수동 병행 평가: 자동 검사도구로 명도 대비·누락 alt를 걸러내고, 스크린리더·키보드 실사용으로 실제 이용 가능성을 검증해 형식 인증의 허점을 보완
3. 인증·거버넌스: WA 품질인증을 획득하고 CI/CD 배포 파이프라인에 접근성 회귀 점검을 넣어 콘텐츠 변경 후에도 준수를 유지(013 리터러시 교육과 연계해 포용 완성)

**결론 (2줄):**
- 기술사 판단: 공공·필수 서비스면 AA를 법적 기준선으로 반드시 확보하고, 특수 목적 콘텐츠에 한해 AAA를 선별 적용하는 것이 현실적임.
- 향후 방향: 모바일·AI 인터페이스 확산으로 접근성 대상이 넓어지므로, 자동 점검 도구화와 설계 단계 내재화(Shift-Left)로 지속 준수 체계를 갖춰야 함.
