# 📖 【암기용】 개념 완전 이해

> 목적: WCAG 2.1이 누구를 위해 어떤 원칙으로 웹을 설계하라고 요구하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: W3C WAI(웹 접근성 이니셔티브)가 제정한 웹 콘텐츠 접근성 지침으로, 장애인·고령자도 웹을 동등하게 이용하도록 하는 국제 표준
- **왜 필요한가**: 시각·청각·운동·인지 장애가 있는 이용자도 온라인 행정·금융·교육 서비스에서 배제되지 않아야 한다
- **핵심 직관**: 건물의 경사로·점자블록이 물리적 접근성을 보장하듯, WCAG는 웹의 디지털 접근성을 보장하는 설계 기준이다

## 깊이 이해
- **배경·문제의식**: 시각적 UI와 마우스 조작 중심으로 설계된 웹은 스크린리더 이용자나 키보드만 쓰는 이용자를 배제할 수 있다
- **작동 원리**: WCAG 2.1은 인식의 용이성(Perceivable), 운용의 용이성(Operable), 이해의 용이성(Understandable), 견고성(Robust) 4대 원칙, 통칭 POUR로 구성되며 각 원칙 아래 지침과 성공기준(success criteria)을 둔다
- **준수 등급**: 최소 수준 A, 중간 수준 AA, 최고 수준 AAA 세 등급으로 나뉘며 등급이 올라갈수록 요구 성공기준이 늘어난다
- **비유**: A는 휠체어가 겨우 지나갈 좁은 경사로, AA는 표준 폭 경사로, AAA는 자동문까지 갖춘 완전 무장애 출입구에 해당한다
- **구체 예시**: 이미지에 대체텍스트(alt) 제공은 인식의 용이성 원칙, 키보드만으로 모든 기능 조작 가능은 운용의 용이성 원칙에 해당한다
- **흔한 오해·주의점**: AAA 등급이 항상 목표는 아니며, 공공기관 웹사이트는 통상 AA 등급 준수를 기본 목표로 삼는 경우가 많다

## 연결 개념
- 한국형 웹 콘텐츠 접근성 지침(KWCAG) — WCAG를 국내 실정에 맞게 반영한 국내 표준
- 장애인차별금지법 — 접근성 미준수를 차별로 규정하는 국내 법적 근거
- 디지털 리터러시 — 접근 가능성과 활용 역량은 상호보완 관계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 디지털 접근성 답안은 POUR 4원칙, 준수 등급(A/AA/AAA), 국내 법제 연계, 검증 방법을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: WCAG 2.1은 인식·운용·이해·견고성 4원칙(POUR)으로 웹 콘텐츠의 장애인 접근성을 규정한 국제 표준이다.
> 2. **가치**: 시각·청각·운동·인지 장애 이용자도 온라인 서비스에 동등하게 접근하도록 보장한다.
> 3. **판단 포인트**: 등급(A/AA/AAA)과 서비스 성격에 맞춰 준수 목표 등급을 정하고 성공기준 충족 여부로 검증해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 표준 구조 이해 확인 | POUR 4원칙과 A/AA/AAA 등급 체계 | 원칙명을 빠뜨리거나 등급 순서를 반대로 서술 |
| 국내 법제 연계 확인 | 장애인차별금지법, KWCAG, 웹접근성 인증 | WCAG만 언급하고 국내 적용 근거 누락 |
| 검증 방법 이해 확인 | 자동 진단 도구 + 전문가·장애인 수동 검증 병행 | 자동 진단만으로 접근성 준수를 판단 |

> 요약: 이 문제는 지침 암기가 아니라 등급별 적용 기준과 국내 법제 연계를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 장애인·고령자의 웹 접근을 보장하는 W3C 국제 접근성 표준
- 배경: 시각·마우스 중심 UI 설계가 스크린리더·키보드 이용자를 배제할 수 있음
- 필요성: 온라인 행정·금융 서비스 확대에 따라 법적 의무와 국제 표준에 기반한 접근성 확보가 요구됨

---

## Ⅱ. 구조 및 구성요소

```text
콘텐츠 설계 -> Perceivable(인식) -> Operable(운용)
            -> Understandable(이해) -> Robust(견고)
  -> 성공기준 충족 -> 준수 등급(A/AA/AAA) 판정
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Perceivable | 정보를 인식 가능한 형태로 제공 | 대체텍스트, 자막, 명도 대비 |
| Operable | 모든 기능을 조작 가능하게 제공 | 키보드 접근, 충분한 조작 시간 |
| Understandable | 콘텐츠와 조작을 이해 가능하게 제공 | 일관된 내비게이션, 오류 안내 |
| Robust | 다양한 보조기기와 호환되게 구현 | 마크업 유효성, 스크린리더 호환 |
| 준수 등급 | 성공기준 충족 수준 구분 | A(최소)-AA(권장)-AAA(최고) |

> 요약: WCAG는 인식·운용·이해·견고 네 원칙 아래 성공기준을 두고 등급으로 준수 수준을 나눈다.

---

## Ⅲ. 동작원리 및 흐름도

```text
서비스 설계·개발 -> POUR 원칙별 성공기준 적용
  -> 자동 진단 도구 점검 -> 전문가·장애인 수동 검증
  -> 결함 수정 -> 웹접근성 인증 신청 -> 인증 획득
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 설계 단계에서 POUR 원칙별 요구사항 반영 | 성공기준 매핑표 |
| 2 | 자동 진단 도구로 마크업·대체텍스트 점검 | 자동 진단 결함 건수 |
| 3 | 장애인·전문가 참여 수동 검증 수행 | 스크린리더 실사용 테스트 결과 |
| 4 | 결함 수정 후 웹접근성 인증 신청 | 인증 심사 통과 여부 |

> 요약: 자동 진단과 장애인 참여 수동 검증을 함께 거쳐야 실질적 접근성이 확보된다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 국제 표준 기반으로 이용자 배제 문제를 체계적으로 예방 | 성공기준 단위로 결함 추적 가능 |
| 한계 | 자동 진단 도구만으로는 실사용성 문제를 모두 잡지 못함 | 수동 검증 병행 필요 |
| 비교 포인트 | WCAG 2.0 대비 모바일·저시력·인지장애 기준이 추가됨 | 신규 서비스는 2.1 이상 기준 적용 검토 |

> 요약: WCAG 2.1은 2.0의 기준을 확장했지만 자동 진단만으로는 완전한 준수를 보장하지 못한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | A 등급 | AA 등급 | AAA 등급 |
|:---|:---|:---|:---|
| 요구 수준 | 최소 성공기준 충족 | 공공기관 표준 목표 수준 | 최고 수준, 전면 적용은 제한적 |
| 적용 대상 | 최소 법적 요건 | 공공·대형 민간 서비스 권장 | 특수 목적 서비스(복지·의료 등) |
| 선택 기준 | 법적 최소 요건만 필요한 경우 | 일반 공공 웹사이트 표준 | 취약계층 전용 서비스에서 선택적 적용 |

> 요약: 공공기관은 통상 AA 등급을 기본 목표로 하고, AAA는 서비스 특성에 따라 선택 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 형식적 준수 | 자동 진단만 통과, 실사용성 미흡 | 장애인 참여 수동 검증 의무화 | 스크린리더 과업 완수율 |
| 신규 콘텐츠 미준수 | 배포 후 콘텐츠 갱신 시 접근성 재검증 누락 | 콘텐츠 등록 프로세스에 접근성 체크 내재화 | 신규 게시물 결함 발생률 |
| 인증 후 방치 | 인증 시점 이후 유지보수 부재 | 정기 재검증 주기 설정 | 재인증 주기 준수율 |

> 요약: 접근성은 인증 취득 시점이 아니라 콘텐츠 갱신·유지보수 전 과정에서 관리해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표준 준수 | AA 등급 성공기준 충족률 | 자동 진단 도구, 체크리스트 |
| 실사용성 | 스크린리더·키보드 과업 완수율 | 장애인 사용성 테스트 |
| 유지관리 | 콘텐츠 갱신 시 재검증 수행률 | 콘텐츠 관리 프로세스 로그 |

> 요약: 도입 성공 여부는 인증 취득이 아니라 실사용성 테스트 완수율과 유지관리 체계로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 신규 서비스 설계 단계부터 POUR 4원칙과 AA 등급 성공기준을 체크리스트로 반영함
2. 자동 진단 도구 점검 후 장애인·전문가가 참여하는 스크린리더 수동 검증을 병행함
3. 콘텐츠 갱신 프로세스에 접근성 재검증 단계를 내재화하고 정기 재인증 주기를 관리함

**결론 (2줄):**
- 기술사 판단: 접근성은 인증 취득이 아니라 실사용성과 유지관리 체계로 판단해야 함
- 향후 방향: 모바일 앱, AI 인터페이스까지 접근성 기준을 확장 적용해야 함

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "WCAG 2.1을 설명하시오" | POUR 원칙과 검증 흐름 | 등급별 차이와 국내 법제 연계 |
| 요구사항 명시형 | "웹 접근성 확보 방안을 제시하시오" | 자동·수동 검증 절차 설계 | 리스크, 지표, 유지관리 체계 |

> 요약: 설명형은 POUR 원칙과 등급 구조, 방안형은 검증 절차와 유지관리 체계 중심으로 답안 축을 바꾼다.
