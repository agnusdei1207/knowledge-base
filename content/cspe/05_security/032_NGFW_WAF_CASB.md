## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 기업의 다양한 네트워크/웹/클라우드 자산을 위협의 특성과 계층에 맞게 세분화하여 방어하는 특수 목적 보안 솔루션들임 |
| **배경/필요성** | 한 가지 방화벽만으로는 정교한 웹 취약점 공격(SQLi)과 섀도우 클라우드 앱 통제를 감당할 수 없어 다계층(Defense-in-Depth) 방어 필요 |
| **출제 의도** | NGFW, WAF, CASB 각각의 보호 대상(네트워크, 웹, 클라우드)과 차별화된 핵심 차단 기능 비교 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  NGFW (네트워크)  |      |     WAF (웹 앱)   |      |  CASB (클라우드)  |
| (L7통제, 앱 제어) +----->| (HTTP 파싱, OWASP)+----->| (SaaS 통제, DLP)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **NGFW (차세대 방화벽)** | 일반 네트워크 트래픽 전체를 포트가 아닌 애플리케이션(BitTorrent, Skype)과 사용자 단위로 통제하는 솔루션임 | 회사 정문의 정밀 X-ray 검색대 |
| **WAF (웹 방화벽)** | HTTP/HTTPS 트래픽만 전문적으로 해부하여 SQL 인젝션, XSS 등 웹 해킹을 막아내는 솔루션임 | 식당 주방의 위생 및 독극물 전담 검사관 |
| **CASB (클라우드 접근 보안)**| 임직원들이 회사 밖의 클라우드(SaaS)를 무단으로 사용하는 것을 감시하고 데이터 유출을 막는 솔루션임 | 외부 출장자의 사제 장비 사용 감시 카메라 |

> 요약: NGFW는 전사 네트워크 외곽을, WAF는 웹 서버의 취약점을, CASB는 직원들의 퍼블릭 클라우드 이용을 방어함.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 트래픽 식별 |-->| 2. 목적별 분기 |-->| 3. 특화 엔진 검사|-->| 4. 조치/리포트 |
| (IP/Port 확인) |   | (웹/비웹/클라우드)|  | (NGFW/WAF/CASB)|   | (차단 및 로깅) |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **트래픽 식별 및 접수**: 외부에서 유입되거나 내부에서 나가는 트래픽의 종류를 1차적으로 확인
2. **솔루션 분기**: 일반 아웃바운드는 NGFW로, 자사 웹 서버를 향하는 인바운드는 WAF로, SaaS 접속은 CASB 프록시로 유도
3. **특화 엔진 검사**:
   - NGFW: 앱 시그니처 매칭, IPS 패턴 검사
   - WAF: URL 파라미터 파싱, SQL 키워드 탐지
   - CASB: API 연동 확인, 중요 데이터(DLP) 포함 여부 분석
4. **조치 및 통합 리포트**: 위반 시 각 장비가 차단 명령을 내리고 중앙 관제 시스템(SIEM)으로 통합 로그를 전송

> 요약: 각 트래픽의 성격에 맞는 최적의 전담 방어 장비로 릴레이하여 정밀하게 요격하는 다계층 프로세스임.

## Ⅳ. 문제점
* **기능 중복에 따른 성능 저하**: NGFW, WAF, 클라우드 프록시가 각각 별도로 트래픽을 복호화/검사하므로 네트워크 병목(Bottle-neck)과 오버헤드 유발
* **운영 정책의 파편화**: 3개의 서로 다른 장비/벤더에서 정책을 따로 설정해야 하므로 관리 복잡성 증가 및 보안 홀(사각지대) 발생
* **On-premise 장비의 한계**: CASB나 WAF 장비를 본사에만 구축할 경우, 재택근무자가 클라우드망에 직접 접속하는 트래픽은 통제할 수 없음

## Ⅴ. 개선방안
* **단기 방안 (SSL 복호화 통합 존)**: 별도의 SSL 가시성 전용 장비를 맨 앞에 배치하여 한 번만 복호화하고 평문을 NGFW, WAF에 동시 미러링하여 병목 제거
* **중기 방안 (통합 정책 관리 플랫폼)**: SOAR 등 보안 오케스트레이션 도구를 도입하여 분산된 솔루션 간의 정책과 위협 인텔리전스를 자동 동기화
* **장기 방안 (SASE/SSE 플랫폼 통합)**: 하드웨어 장비를 폐기하고 NGFW(FWaaS), WAF, CASB를 단일 클라우드 에이전트 서비스(SASE)로 통합 구독하여 장소 제약 해소

## Ⅵ. 전망
* 벤더 간의 합병이 가속화되면서, 개별 장비로 존재하던 NGFW, WAF, CASB가 클라우드 엣지 기반의 단일 '보안 서비스 엣지(SSE)' 플랫폼으로 완전히 흡수 통합되는 추세임
* 제로 트러스트(ZTA) 사상에 기반하여, 접속 기기의 포스처(상태)와 결합된 동적인 클라우드 보안 통제가 엔터프라이즈의 표준 아키텍처로 자리매김함
