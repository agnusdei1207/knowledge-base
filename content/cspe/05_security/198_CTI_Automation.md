## Ⅰ. 개요
- 정의: 글로벌 사이버 위협 인텔리전스(CTI)에서 발생하는 방대한 IoC(IP, 해시, URL) 및 해커 전술 정보를 수동 분석 없이 플랫폼(TIP)을 통해 즉각 수집, 분석, 방어 장비에 자동 배포하는 체계임.
- 배경/필요성: 해커는 매분 수백만 개의 악성 도메인을 생성하여 공격하나, 보안 인력이 이를 매일 수동으로 방화벽에 등록하는 것은 물리적으로 불가능하여 머신 대 머신(Machine-to-Machine) 대응 필수.
- 출제 의도: 외부 위협 정보를 내부 방어막에 통합하는 TIP(위협 인텔리전스 플랫폼)의 역할과, 이를 통한 보안 운영 생명주기의 자동화 가치를 묻는 문제임.

## Ⅱ. 구성요소
+-------------------+       +-------------------+       +-------------------+
| 위협 피드 수집    | ----> | TIP (인텔리전스)  | ----> | 방어 장비(SIEM 등)|
| (OSINT, 상용피드) |       | (정규화, 평판스코어)|     | (자동 룰 배포차단)|
+-------------------+       +-------------------+       +-------------------+

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 다기종 위협 피드 (Feeds) | STIX/TAXII 포맷 등으로 제공되는 상용 인텔리전스, 오픈소스(OSINT) 등의 위협 데이터 소스 | 전 세계의 수배자 명단 데이터베이스 |
| TIP (위협 인텔리전스 플랫폼) | 쏟아지는 수만 개의 데이터를 중복 제거, 정규화, 신뢰도 평가하여 우리 회사에 맞는 알짜 정보만 추출하는 플랫폼 | 정보국의 데이터 분석 및 정제 센터 |
| 연동 및 자동 방어 (Integration) | 정제된 악성 IP나 해시값을 사내 방화벽, IPS, EDR 등 보안 장비의 블랙리스트로 자동 전송(API) | 출입국 관리소의 블랙리스트 자동 업데이트 |

> 요약: 전 세계의 위협 정보를 플랫폼에서 정제 및 선별한 뒤, 수동 작업 없이 회사 방어 장비에 곧바로 차단 룰로 넘김.

## Ⅲ. 절차
+-------------------+   +-------------------+   +-------------------+   +-------------------+
| 1. 멀티 소스 수집 |-->| 2. 데이터 정규화  |-->| 3. 위협 헌팅/매칭 |-->| 4. 자동 차단 배포 |
+-------------------+   +-------------------+   +-------------------+   +-------------------+

1. 멀티 소스 수집: 여러 인텔리전스 공급업체(Vendor)와 블로그, 트위터(OSINT)에서 실시간으로 발생하는 IoC 피드 자동 수집
2. 데이터 정규화(TIP): 형식(Format)이 제각각인 데이터를 표준 규격(STIX 등)으로 맞추고, 오탐(정상 구글 IP 등)을 제거하여 신뢰도 스코어 부여
3. 위협 헌팅/매칭: 정제된 위협 IoC를 내부의 SIEM(로그 저장소)과 대조하여 이미 과거에 우리 내부망과 통신한 이력이 있는지 자동 스캔
4. 자동 차단 배포: 신뢰도가 높고 치명적인 악성 IP와 도메인 목록을 SOAR 등과 연동하여 방화벽 및 DNS 필터링 솔루션에 10분 주기로 자동 업데이트

> 요약: 위협 피드를 긁어모아 오탐을 걸러내고, 내부망 침투 여부를 검색한 뒤 방어 장비에 블랙리스트를 심어줌.

## Ⅳ. 문제점
- 피드 품질의 한계 (Garbage In, Garbage Out): 돈을 주고 산 CTI 피드라도 만료되거나 정상 클라우드 IP가 섞여 있어(False Positive), 이로 인해 사내 중요 업무 시스템 접속이 원천 차단되는 대형 장애 발생 우려
- 기술적 파편화: 국내 방화벽이나 구형 레거시 장비는 표준 API나 STIX/TAXII 규격을 지원하지 않아 자동 연동이 불가능하고 결국 수동 등록 필요
- 맹목적 IoC 의존: 단순 IP/해시값 기반 차단은 공격자가 도메인만 바꾸면 우회되므로, 근본적인 공격 그룹의 전술(TTPs) 파악 체계로는 부족함
- 투자 대비 효용 입증: 막대한 TIP 도입 및 상용 피드 구독 비용 대비, 실제로 막아낸 공격이 얼마나 치명적이었는지 C-레벨에게 ROI(투자수익률)로 증명하기 어려움

## Ⅴ. 개선방안
- 단기: 무차별적인 자동 차단(Blocking) 대신 최초 1주일은 '탐지(Alert Only)' 모드로 운영하여 피드의 품질(오탐율)을 검증한 후 차단(Block) 모드로 전환
- 중기: 자사의 산업군(예: 금융, 제조)에 특화된 피드만을 선별 적용하고, 동종 업계 간 ISAC(정보공유분석센터)을 통한 자체 CTI 정보 공유 강화
- 장기: 단순 IoC 자동화를 넘어, LLM/AI를 적용해 해커의 TTPs 보고서를 분석하고 사내 MITRE ATT&CK 방어 매핑 지표를 실시간으로 업데이트하는 시맨틱 CTI 체계로 진화

## Ⅵ. 전망
- SOAR 플랫폼 내에 TIP 엔진이 기본 내장(Built-in)되는 추세가 가속화되며, 위협 수집과 대응의 경계가 완전히 허물어질 것임.
- AI 해커의 다형성 악성코드(도메인 수시 변경) 생성 속도에 맞서기 위해, AI 기반 CTI가 공격자의 알고리즘을 예측해 선제 차단하는 AI 대 AI의 전쟁이 본격화될 전망임.
