# 📖 【암기용】 개념 완전 이해

> 목적: CIA Triad를 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 기밀성·무결성·가용성을 기준으로 보안 목표와 통제를 설계하는 기본 판단 축
- **왜 필요한가**: 보안 대책은 모든 것을 동시에 최대화할 수 없다. 개인정보 시스템은 기밀성, 금융 원장은 무결성, OT 제어망은 가용성과 안전이 우선될 수 있다.
- **핵심 직관**: CIA Triad는 "무엇을 먼저 지킬 것인가"를 정하는 보안 아키텍처의 나침반이다.

## 깊이 이해
- **배경·문제의식**: 암호화, 접근통제, 백업, 모니터링은 목적이 다르다. 목적을 구분하지 않으면 개인정보에는 백업만 하고, 결제 시스템에는 암호화만 하는 식으로 통제가 어긋난다.
- **작동 원리**: Confidentiality는 허가된 주체만 보게 하는 목표이고, Integrity는 데이터와 명령이 허가 없이 바뀌지 않게 하는 목표이며, Availability는 필요한 시간에 서비스를 사용할 수 있게 하는 목표이다. 아키텍처는 자산별 CIA 우선순위를 정하고 통제를 매핑한다.
- **비유**: 금고는 내용물을 숨기고, 봉인은 내용물이 바뀌지 않았음을 보이며, 비상 발전기는 정전에도 서비스를 유지한다. 세 장치는 목적이 다르다.
- **구체 예시**: 의료 데이터 레이크는 AES-256, RBAC, 감사로그로 기밀성을 우선한다. 결제 원장은 HMAC, WORM 로그, 이중 승인으로 무결성을 우선한다. 클라우드 API는 Multi-AZ, RTO 30분, RPO 5분으로 가용성을 관리한다.
- **흔한 오해·주의점**: CIA는 모든 시스템에 같은 순서로 적용하는 암기 항목이 아니다. OT, 클라우드, AI에서는 우선순위와 지표가 달라진다.

## 연결 개념
- Zero Trust - 기밀성·무결성 중심 접근통제 구조
- BCP/DR - 가용성 목표인 RTO/RPO 관리
- Data Governance - 데이터 기밀성·무결성 책임 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 수치·표준·도식·문제유형 전환을 엄격히 적용한다.
> 핵심: CIA Triad는 보안 목표 암기가 아니라 시스템 유형별 우선순위와 통제 매핑을 판단하는 아키텍처 프레임이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CIA Triad는 Confidentiality, Integrity, Availability를 기준으로 자산 보호 목표와 보안 통제를 분류하는 보안 아키텍처 판단 축이다.
> 2. **가치**: 암호화·접근통제·전자서명·백업·DR·모니터링을 자산별 목표에 맞게 배치해 과잉통제와 누락통제를 줄인다.
> 3. **판단 포인트**: OT는 Availability/Integrity, 클라우드는 Availability/Confidentiality, AI는 Integrity/Confidentiality 우선순위가 달라질 수 있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 목표 분류 역량 확인 | C/I/A 각각의 보호 대상과 대표 통제 | 세 단어 풀이만 쓰고 통제 매핑 누락 |
| 아키텍처 적용 판단 확인 | 자산별 우선순위, 지표, 예외 조건 | 모든 시스템에 동일 순서 적용 |
| 환경별 우선순위 전환 확인 | OT, 클라우드, AI에서 우선 목표 변화 | 기밀성만 보안 목표로 단정 |

> 요약: 이 문제는 CIA를 외우는 것이 아니라 시스템 맥락별 보안 목표와 지표를 선택하는 판단력을 요구한다.

## Ⅰ. 개요 및 필요성

CIA Triad는 기밀성·무결성·가용성을 보안 목표의 기본 축으로 삼는 아키텍처 프레임이다. 보안 대책은 자산 가치와 업무 영향에 따라 우선순위가 달라진다. 따라서 설계자는 자산별 CIA 목표를 먼저 정하고 통제·지표·운영 절차를 매핑해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Asset Classification -> CIA Priority -> Control Mapping
-> Metric Definition -> Monitoring -> Risk Treatment
Data / System / AI Model / OT Process -> C / I / A Weighting
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Confidentiality | 허가된 주체만 정보 접근 | AES-256, RBAC, DLP, 마스킹 |
| Integrity | 데이터·명령·모델 변경의 정당성 보장 | Hash, HMAC, 전자서명, WORM |
| Availability | 업무 시간 내 서비스·공정 사용 보장 | Multi-AZ, DR, RTO/RPO, DDoS 방어 |
| Priority Model | 자산별 우선 목표 결정 | OT·클라우드·AI별 순서 전환 |

> 요약: CIA 구조는 보호 목표를 세 축으로 나누고 자산별 우선순위에 맞춰 통제를 배치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산 식별 -> 업무 영향 분석 -> CIA 우선순위 결정
-> 통제 매핑 -> 지표 설정 -> 모니터링·감사
-> 사고 대응 -> 우선순위 재조정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터·시스템·모델·OT 공정 자산 식별 | 자산 목록 최신성 95% 이상 |
| 2 | 침해 시 영향도와 법적 요구사항 분석 | 개인정보·금융·안전 영향 분류 |
| 3 | CIA 우선순위와 허용 위험 결정 | 자산별 1순위 목표 명시 |
| 4 | 통제와 측정 지표 매핑 | 통제 커버리지 100% |
| 5 | 모니터링·감사·복구 훈련 수행 | 감사로그 보존 1년 이상 |

> 요약: CIA는 자산 식별에서 지표 운영까지 이어지는 보안 설계 절차의 기준선이다.

## Ⅳ. 특징

| 구분 | 기밀성 중심 | 무결성 중심 | 가용성 중심 |
|:---|:---|:---|:---|
| 대표 자산 | 개인정보, 영업비밀, API Key | 결제 원장, 배포물, AI 학습데이터 | OT 제어망, 클라우드 서비스 |
| 대표 통제 | 암호화, RBAC, DLP | 전자서명, Hash, WORM 로그 | Multi-AZ, DR, DDoS 방어 |
| 대표 지표 | 미승인 접근 0건 | 변조 탐지 100%, 승인 변경률 | RTO 30분, RPO 5분, 가용성 99.9% |
| 환경 예시 | 의료·공공 데이터 | 금융·공급망·AI 모델 | 제조·전력·SaaS |

> 요약: CIA의 가치는 자산 유형에 따라 서로 다른 통제와 측정 지표를 선택하게 하는 데 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | CIA Triad 적용 | 선택 기준 |
|:---|:---|:---|:---|
| OT | 기밀성 우선 보안 | 가용성·무결성 우선 | 안전·생산 중단 영향 존재 시 |
| 클라우드 | 단일 보안통제 | Multi-AZ, IAM, 암호화 조합 | RTO/RPO와 개인정보 동시 요구 시 |
| AI | 모델 정확도 중심 | 데이터·모델 무결성, 프롬프트 기밀성 | 학습데이터 오염·모델 유출 위험 시 |

> 요약: CIA 우선순위는 산업과 자산에 따라 전환되며, 그 전환을 설명하는 것이 기술사 답안의 핵심이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 기밀성 침해 | 과도한 권한, 평문 저장 | RBAC, AES-256, KMS, DLP | 미승인 접근 0건 |
| 무결성 훼손 | 배포물 변조, 데이터 오염 | 서명 검증, WORM, 승인 워크플로 | 변조 탐지율 100% |
| 가용성 저하 | 장애, DDoS, 복구 미흡 | Multi-AZ, WAF/CDN, DR 훈련 | RTO 30분, RPO 5분 |

> 요약: CIA별 리스크는 원인과 통제가 다르므로 하나의 보안 제품으로 해결된다고 볼 수 없다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 기밀성 | 개인정보 접근권한 분기 1회 검토 | IAM 리포트, DLP 로그 |
| 무결성 | 배포물 서명 검증 100%, 감사로그 위변조 방지 | CI/CD 로그, WORM 저장소 |
| 가용성 | 서비스 가용성 99.9%, DR 훈련 반기 1회 | APM, 장애 리포트, DR 결과 |

> 요약: CIA 운영은 각 축마다 접근권한, 서명 검증, RTO/RPO처럼 다른 지표로 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 자산 분류표에 C/I/A 우선순위와 목표 지표를 기록하고, 개인정보는 AES-256·RBAC, 결제 원장은 전자서명·WORM 적용
2. 클라우드 서비스는 Multi-AZ, 백업 주기 15분, RTO 30분, RPO 5분 기준으로 가용성 통제를 설계
3. AI 시스템은 학습데이터 Hash, 모델 서명, 프롬프트 접근통제, 출력 감사로그로 무결성과 기밀성을 동시 관리

**결론 (2줄):**
- 기술사 판단: 개인정보 시스템은 C 우선, 금융·AI 데이터는 I 우선, OT·공공서비스는 A 우선으로 통제 우선순위를 전환함
- 향후 방향: Zero Trust, 클라우드 DR, AI 보안이 확산되며 CIA는 단순 원칙에서 자산별 지표 기반 아키텍처 판단 기준으로 고도화됨
