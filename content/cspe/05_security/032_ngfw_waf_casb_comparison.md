## 미리 알고가기

- App-ID: 포트 번호가 아니라 실제 애플리케이션 종류를 식별하는 기능임
- OWASP Top 10: 웹 애플리케이션에서 자주 문제가 되는 대표 취약점 분류임
- Shadow IT: IT 부서 통제 밖에서 사용되는 비인가 SaaS와 클라우드 서비스임
- SSL 복호화: 암호화된 트래픽을 정책 검사 후 다시 암호화하는 중간 검사용 절차임

## Ⅰ. 개요

- **정의/개념**: NGFW, WAF, CASB는 모두 심층 보안을 위한 통제 장치이지만, NGFW는 네트워크 출입구, WAF는 웹 애플리케이션 앞단, CASB는 SaaS와 클라우드 사용 경계라는 서로 다른 지점을 보호하는 목적 특화 솔루션임
- **배경/필요성**: 공격이 80/443 포트 안으로 숨어들고 업무 자산이 웹과 SaaS로 이동하면서, 경계 방화벽 하나만으로는 네트워크·웹·클라우드의 서로 다른 위험을 모두 통제할 수 없게 됨

## Ⅱ. 특징

- 세 솔루션은 경쟁 장비가 아니라 보호 대상과 배치 위치가 다른 보완재임
- NGFW는 사용자와 앱 단위로 네트워크 트래픽을 통제하고, WAF는 HTTP 요청 내용 자체를 이해하며, CASB는 SaaS 사용 행태와 데이터 이동을 통제함
- 세 장비 모두 암호화 트래픽을 제대로 보려면 복호화 또는 API 연동 같은 추가 운영 설계가 필요함
- 잘못 선택하면 장비가 있는데도 위협 지점이 비어 있으므로, 무엇을 보호하려는지 먼저 명확히 해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | NGFW | WAF | CASB |
|:---|:---|:---|:---|
| 주 보호 지점 | 인터넷 출입구와 내부 구역 사이 네트워크 경계 | 웹 서버와 API 서비스 바로 앞단 | 사용자와 SaaS/클라우드 서비스 사이 |
| 주로 막는 위험 | 악성 애플리케이션, 비인가 트래픽, 기본 네트워크 위협 | SQL Injection, XSS, 봇, 웹 요청 악용 | 데이터 유출, 비인가 SaaS 사용, 계정 오남용 |
| 판단 근거 | 앱 식별, 사용자 식별, IPS 정책 | HTTP 파라미터, 헤더, 세션, 웹 취약점 패턴 | API 이벤트, 업로드 행위, 접근 정책, DLP 규칙 |
| 특히 적합한 상황 | 사내망 출입 통제와 네트워크 세그먼트 보호 | 인터넷 공개 웹 서비스와 API 보호 | M365, Google Workspace, Slack 같은 SaaS 거버넌스 |

> 요약: NGFW는 네트워크 경계, WAF는 웹 요청, CASB는 SaaS 사용과 데이터 이동을 보는 장비임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| NGFW 계층 | 사용자와 애플리케이션 기준으로 트래픽을 분류하고 출입을 통제하는 첫 관문 역할을 함 |
| WAF 계층 | 웹 요청의 파라미터와 세션을 분석해 애플리케이션 취약점 악용을 차단함 |
| CASB 계층 | SaaS API나 프록시 방식으로 계정 활동과 데이터 이동을 추적하고 통제함 |
| 공통 정책 계층 | 사용자 그룹, 데이터 분류, 예외 승인, 감사 로그를 통합해 각 계층 정책을 일관되게 유지함 |

```text
+--------+     +------+     +------+     +------+
| 사용자 | --> | NGFW | --> | WAF  | --> | 웹앱 |
+--------+     +------+     +------+     +------+
    |
    +--------------------> +------+
                           | CASB |
                           +------+
                                |
                           +---------+
                           | SaaS/클라우드 |
                           +---------+
```

> 요약: 네트워크 경계는 NGFW, 웹 요청은 WAF, SaaS 사용은 CASB가 맡고 정책은 공통 계층에서 정리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 자산 식별 | --> | 보호 지점 선택 | --> | 정책 적용 | --> | 가시성 확보 | --> | 지속 튜닝 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **자산 식별**: 웹 서비스, 내부망, SaaS 가운데 무엇을 보호할지 정함
2. **보호 지점 선택**: 경계망은 NGFW, 웹 앞단은 WAF, SaaS 사용은 CASB로 나눔
3. **정책 적용**: 사용자, 앱, 데이터 분류 기준으로 제어 규칙을 세움
4. **가시성 확보**: SSL 복호화나 API 연동으로 실제 내용을 볼 수 있게 함
5. **지속 튜닝**: 오탐과 미탐을 줄이며 예외 정책을 관리함

## Ⅵ. 실무 적용 및 유의점

1. 인터넷 공개 서비스는 NGFW만으로 웹 공격을 막기 어려우므로 네트워크 경계에는 NGFW를 두고 웹·API 바로 앞에는 WAF를 별도로 배치하며 SSL 복호화와 봇 정책을 함께 운영하고 차단율, 응답 지연, 오탐 재처리 건수로 확인함
2. SaaS 중심 협업 환경에서는 방화벽이 있어도 파일 유출과 Shadow IT 통제가 비므로 CASB를 DLP와 계정 정책에 연결하고 비인가 SaaS 탐지 건수, 민감 파일 업로드 차단율, 관리자 승인 예외 건수로 확인함

## Ⅶ. 결론

NGFW, WAF, CASB의 선택 기준은 장비 기능 비교보다 보호 자산이 네트워크 경계에 있는지, 웹 요청에 있는지, SaaS 데이터 이동에 있는지부터 나누는 데 있음.
