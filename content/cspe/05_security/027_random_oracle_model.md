## 미리 알고가기

- 오라클: 알고리즘이 질의하면 응답을 돌려주는 가상의 함수 인터페이스임
- 환원 증명: 어떤 공격이 가능하다면 더 어려운 수학 문제도 풀린다고 연결해 안전성을 설명하는 방식임
- 인스턴스화: 가상 오라클 자리에 실제 해시 함수 같은 구체 구현을 넣는 과정임
- Fiat-Shamir: 대화형 증명을 해시 함수로 비대화형 구조로 바꾸는 기법임

## Ⅰ. 개요

- **정의/개념**: 랜덤 오라클 모델은 해시 함수를 이상적 무작위 블랙박스로 가정해 암호 프로토콜 안전성을 분석하는 방법론임
- **배경/필요성**: 실제 해시 내부 구조까지 반영한 증명은 어려움. 실용 프로토콜 설계를 위한 중간 가정이 필요함

## Ⅱ. 특징

- 해시 함수를 이상화해 증명을 단순화하고 실용 프로토콜 설계를 돕음
- ROM 안전성은 실제 해시 구현의 안전성을 자동 보장하지 않음
- Fiat-Shamir, RSA-OAEP, 여러 서명 스킴에서 자주 쓰임
- 장기 고신뢰 환경은 ROM 가정과 실제 해시 선택을 함께 검토해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 표준 모델 | 랜덤 오라클 모델 |
|:---|:---|:---|
| 증명 가정 | 해시를 포함한 모든 요소를 구체적 수학 구조 안에서 다룸 | 해시를 이상적 무작위 오라클로 가정하고 증명함 |
| 설계 난이도 | 증명이 까다롭고 효율 좋은 설계를 만들기 어려운 편임 | 증명과 설계가 단순해져 실용 프로토콜을 만들기 쉬움 |
| 현실 해석 | 가정이 적어 이론적으로 더 엄격함 | 실제 해시 함수가 가정을 얼마나 잘 대체하는지 추가 해석이 필요함 |
| 적합한 상황 | 고강도 이론 보증이 중요한 경우에 맞음 | 실용성과 증명 가능성을 함께 잡아야 하는 경우에 맞음 |

> 요약: 표준 모델은 엄격하지만 어렵고, ROM은 실용적이지만 해시 인스턴스화 한계를 함께 봐야 함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 랜덤 오라클 | 새로운 입력에는 무작위 출력을 주고 같은 입력에는 항상 같은 출력을 돌려주는 이상적 함수 가정임 |
| 적대자 모델 | 공격자가 오라클에 질의하며 프로토콜을 깨려는 존재이며 질의 횟수와 능력이 증명 조건이 됨 |
| 환원기 | 적대자가 프로토콜을 깨면 근본 난제도 풀린다고 연결하는 증명 장치임 |
| 실제 해시 함수 | 구현 단계에서 SHA-2, SHA-3 같은 함수로 오라클을 대체하며 이 지점이 이론과 현실의 연결부가 됨 |

```text
+--------+     +---------------+     +-----------+     +-----------+
| 적대자 | --> | 랜덤 오라클 질의 | --> | 프로토콜 공격 | --> | 환원 증명 |
+--------+     +---------------+     +-----------+     +-----------+
                                             |
                                      +-------------+
                                      | 실제 해시 대체 |
                                      +-------------+
```

> 요약: 적대자가 오라클 질의를 활용해 공격하더라도 환원 증명이 성립하는지를 보는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 프로토콜 설계 | --> | ROM 가정  | --> | 환원 증명 | --> | 해시 대체 | --> | 구현 검토 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **프로토콜 설계**: 해시 함수가 들어가는 암호 프로토콜을 정의함
2. **ROM 가정**: 해시를 이상적 오라클로 가정함
3. **환원 증명**: 공격 가능성을 근본 난제 해결 가능성과 연결함
4. **해시 대체**: 실제 해시 함수로 인스턴스화함
5. **구현 검토**: 길이 확장, 충돌, 파라미터 선택 같은 현실 위험을 다시 점검함

## Ⅵ. 실무 적용 및 유의점

1. Fiat-Shamir·ZKP·RSA-OAEP는 해시 수명주기와 도메인 분리를 관리하고 취약 해시·파라미터·재평가 주기로 확인함
2. 장기 인증 인프라는 표준 모델 대안과 해시 교체성을 설계하고 교체 시간·호환성 영향·감사 적합성으로 확인함

## Ⅶ. 결론

- 랜덤 오라클 모델은 실용 암호 설계 도구이지만 실제 해시 함수와 인스턴스화 규칙 관리가 실무 안전성을 좌우함
