## 미리 알고가기

- 스트림 암호: 평문과 길이가 같은 키 스트림을 만들어 XOR로 암호화하는 방식임
- nonce: 같은 키 아래에서 세션마다 바꿔야 하는 일회성 값임
- counter: 블록마다 증가하며 서로 다른 키 스트림 블록을 만드는 값임
- Poly1305: ChaCha20과 함께 무결성을 붙이는 메시지 인증 방식임

## Ⅰ. 개요

- **정의/개념**: ChaCha20은 256비트 키, nonce, counter로 키 스트림을 만들고 평문과 XOR하는 스트림 암호임
- **배경/필요성**: AES 가속기가 없는 모바일·임베디드 환경은 AES 성능이 낮을 수 있음. 범용 CPU에 강한 대체 암호가 필요함

## Ⅱ. 특징

- 덧셈, XOR, 회전만 사용해 소프트웨어 구현이 빠름
- 스트림 암호라 패딩 없이 임의 길이 데이터를 처리함
- 같은 키와 nonce를 재사용하면 키 스트림이 반복되어 치명적임
- 단독 사용은 기밀성만 제공하므로 Poly1305 AEAD 결합이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | AES-GCM | ChaCha20-Poly1305 |
|:---|:---|:---|
| 연산 특성 | AES 전용 명령어가 있으면 매우 빠름 | 범용 CPU에서도 안정적으로 빠른 성능을 내기 쉬움 |
| 구현 적합성 | 하드웨어 가속 유무에 따라 성능 차이가 큼 | 모바일, 임베디드, 소프트웨어 구현 환경에 강함 |
| nonce 관리 | GCM도 nonce 재사용이 치명적임 | 같은 키와 nonce를 재사용하면 키 스트림이 반복돼 위험함 |
| 선택 기준 | 서버급 CPU에 AES 가속이 충분할 때 맞음 | 가속기 없는 단말이나 균일한 소프트웨어 성능이 중요할 때 맞음 |

> 요약: AES-GCM은 가속기 환경에 강하고, ChaCha20-Poly1305는 소프트웨어 중심 환경에서 예측 가능한 성능을 줌.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 256비트 키 | 전체 키 스트림을 결정하는 비밀값이며 노출되면 모든 세션 보호가 무너짐 |
| nonce | 같은 키 아래에서 세션을 구분하는 값이며 재사용을 막는 운영 정책이 가장 중요함 |
| counter | 블록마다 증가하며 각 블록에 서로 다른 키 스트림을 공급함 |
| ChaCha 상태 행렬 | 상수, 키, counter, nonce를 조합한 내부 상태이며 라운드를 거쳐 키 스트림 블록을 생성함 |

```text
+--------+     +-------+     +---------+     +-------------+
|  키    | --> | nonce | --> | counter | --> | 키 스트림 생성 |
+--------+     +-------+     +---------+     +-------------+
                                                  |
                                           +-------------+
                                           | 평문과 XOR  |
                                           +-------------+
```

> 요약: 키, nonce, counter를 상태에 넣어 키 스트림을 만들고 평문과 XOR해 암호문을 생성함.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 상태 초기화 | --> | 라운드 연산 | --> | 키 스트림 생성 | --> | XOR 암호화 | --> | 태그 부여 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **상태 초기화**: 키, nonce, counter를 내부 상태에 배치함
2. **라운드 연산**: quarter-round를 반복해 상태를 섞음
3. **키 스트림 생성**: 현재 블록용 키 스트림을 만듦
4. **XOR 암호화**: 평문과 키 스트림을 XOR해 암호문을 생성함
5. **태그 부여**: 실무에서는 Poly1305로 무결성 태그를 붙임

## Ⅵ. 실무 적용 및 유의점

1. 모바일 TLS·QUIC·VPN은 전송 시퀀스와 nonce 규칙을 묶어 관리하고 처리량·배터리·nonce 충돌로 확인함
2. 라이브러리는 ChaCha20-Poly1305 AEAD를 사용하고 복호화 실패율·태그 오류·상수시간 점검으로 확인함

## Ⅶ. 결론

- ChaCha20은 소프트웨어 성능이 강점이지만 nonce 재사용 금지와 인증 결합을 운영으로 보장해야 함
