## Ⅰ. 개요
- **정의**: CVE는 취약점 고유 식별 체계, CVSS는 취약점 심각도를 수치화하는 점수 체계
- **배경/필요성**: 취약점 정보를 조직 간 일관되게 공유하고 대응 우선순위를 객관화할 기준이 필요함
- **비유**: CVE는 질병의 고유 코드, CVSS는 해당 질병의 위험도 등급

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 식별-평가 체계의 구조와 활용 | CVE 번호 체계, CVSS 메트릭 구성 | CVSS v3.1과 v4.0 차이 언급 필요 |

> 요약: CVE로 취약점을 식별하고 CVSS로 심각도를 정량화하여 대응 우선순위를 결정함

## Ⅱ. 구성요소
```text
+-----------+     +-------------------+
| CVE ID    | --> | CVSS Score        |
| CVE-YYYY- |     | Base/Temporal/Env |
| NNNNN     |     +---+-------+-------+
+-----------+         |       |
                      v       v
                  Priority  Patch Plan
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CVE ID | `CVE-연도-번호` 형식의 취약점 고유 식별자 | 질병 분류 코드 |
| Base Score | 공격 벡터·복잡도·영향도를 반영한 기본 점수(0~10) | 질병 기본 위험 등급 |
| Temporal/Environmental | 패치 가용성·조직 환경을 반영한 보정 점수 | 환자 상태별 위험 조정 |

> 요약: CVE ID로 식별하고 CVSS의 3개 메트릭 그룹으로 심각도를 산정함

## Ⅲ. 절차
```text
취약점 발견 -> CVE 할당 -> CVSS 산정 -> 대응 우선순위 결정
```
- 1단계: 연구자·벤더가 취약점을 발견하고 CNA에 보고
- 2단계: CNA가 CVE ID를 할당하고 취약점 정보를 공개
- 3단계: Base·Temporal·Environmental 메트릭으로 CVSS 점수 산정
- 4단계: 점수 기반으로 패치 우선순위를 결정하고 조치 계획 수립

> 요약: 발견-식별-평가-우선순위의 4단계로 취약점 대응 체계를 운영함

## Ⅳ. 문제점
- 점수 과신: CVSS 점수만으로 우선순위 결정 — 실제 악용 가능성 미반영
- 할당 지연: CVE 신청 후 ID 할당까지 시간 소요 — 제로데이 대응 공백 발생
- 환경 메트릭 미활용: 조직별 환경 점수 미산정 — 범용 점수로만 판단하여 왜곡 발생

> 요약: 점수 과신·할당 지연·환경 미반영이 대응 실효성을 저하시킴

## Ⅴ. 개선방안
1. 단기: EPSS(악용 예측 점수)를 CVSS와 병행하여 실제 위협 기반 우선순위 산정
2. 중기: 자동화 도구로 CVE 공개 즉시 자산 영향도를 자동 매핑
3. 장기: 조직별 Environmental 메트릭을 자산 인벤토리와 연동하여 자동 산정

> 요약: EPSS 병행·자동 매핑·환경 메트릭 자동화로 정밀한 우선순위를 확보함

## Ⅵ. 전망
- 발전 방향: CVSS v4.0 도입으로 Supplemental 메트릭이 추가되어 정밀도 향상 예상
- 기술사적 판단: CVE/CVSS는 취약점 관리의 공통 언어로서 지속 활용될 것임
- 기술사 제언: CVSS 단독이 아닌 EPSS·KEV 카탈로그와 결합한 다차원 평가를 제언함
