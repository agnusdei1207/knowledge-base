# 📖 【암기용】 개념 완전 이해

> 목적: 디스크 이미징·해시 무결성을 처음 보는 사람도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 저장매체를 비트 단위로 복제하고 해시값으로 원본 동일성을 검증하는 포렌식 절차
- **왜 필요한가**: 원본 디스크를 직접 분석하면 파일 접근 시각, 저널, 메타데이터가 바뀔 수 있다. 사본 분석과 해시 검증으로 증거 훼손 주장을 막는다.
- **핵심 직관**: 디스크 이미지는 원본의 복사본이고, 해시는 봉인 스티커처럼 복사 전후 변경 여부를 확인한다.

## 깊이 이해
- **배경·문제의식**: 포렌식 분석은 파일을 열고 검색하고 복구하는 작업이므로 원본을 보호해야 한다. NIST CFTT는 디스크 이미징 도구의 정확성을 시험하고, SWGDE는 획득 데이터 해시 비교로 무결성을 확인하도록 권고한다.
- **작동 원리**: 원본 매체에 쓰기방지 장치를 연결하고 비트스트림 이미지를 생성한다. 획득 전후 또는 소스와 이미지의 SHA-256 해시를 기록해 사본이 원본과 같은지 검증한다.
- **비유**: 계약서 원본은 금고에 넣고 공증된 사본으로 검토하는 방식이다. 사본이 원본과 같은지는 페이지 수보다 지문 같은 해시값으로 확인한다.
- **구체 예시**: 1TB SSD를 E01 또는 RAW 형식으로 이미징하고 SHA-256 해시가 원본과 이미지에서 일치하면 분석자는 이미지 파일만 마운트해 타임라인을 작성한다.
- **흔한 오해·주의점**: 해시 일치가 분석 결론의 정확성을 보장하지는 않는다. 해시는 수집 무결성을 검증하고, 분석 결론은 도구 검증과 절차 재현성으로 뒷받침한다.

## 연결 개념
- 디지털 포렌식 - 이미징과 해시 검증을 포함하는 상위 절차
- 체인 오브 커스터디 - 이미지 파일과 원본 매체 인계 기록
- FIPS 180-4 - SHA-256 등 보안 해시 알고리즘 표준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 디스크 이미징은 복사 기술이 아니라 원본 보존, 쓰기방지, 해시 검증, 도구 검증을 결합한 증거 무결성 절차이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 디스크 이미징은 저장매체를 비트 단위로 복제하고 해시 무결성으로 원본과 사본의 동일성을 입증하는 절차이다.
> 2. **가치**: SHA-256, 쓰기방지, 이미지 포맷, 도구 로그로 증거 훼손·변조 가능성을 낮춘다.
> 3. **판단 포인트**: 원본 보존과 분석 사본 분리, 불량 섹터·HPA/DCO 기록, 도구 검증 여부를 함께 봐야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 무결성 검증 이해 확인 | 원본 해시, 이미지 해시, SHA-256, 쓰기방지 | MD5만 쓰고 충돌·표준 이슈 누락 |
| 포렌식 획득 절차 확인 | 비트스트림 이미지, E01/RAW, 로그, 오류 섹터 | 일반 파일 복사와 혼동 |
| 증거능력 판단 확인 | 원본 보존, 분석 사본, 체인 오브 커스터디 | 원본 디스크 직접 마운트 |

> 요약: 이 문제는 디스크 복제가 아니라 무결성 검증과 증거 보존 절차를 함께 묻는다.

---

## Ⅰ. 개요 및 필요성

디스크 이미징·해시 무결성은 저장매체를 포렌식 사본으로 생성하고 해시값으로 동일성을 검증하는 절차이다. 디지털 증거는 분석 중 메타데이터가 바뀔 수 있어 원본 보존이 필요하다. SHA-256 해시, 쓰기방지, 오류 기록은 증거능력 확보의 핵심 근거이다.

---

## Ⅱ. 구조 및 구성요소

```text
원본 저장매체 -> 쓰기방지 -> 이미징 도구 -> 포렌식 이미지
             +-> SHA-256 계산 -> 해시 로그/체인 오브 커스터디
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 원본 저장매체 | HDD, SSD, USB, 서버 볼륨 증거 원천 | 모델, 일련번호, 용량 기록 |
| 쓰기방지 장치 | 원본 매체에 쓰기 명령 차단 | 하드웨어 write blocker 권장 |
| 이미징 도구 | RAW, E01, AFF 등 이미지 생성 | 도구명·버전·설정 기록 |
| 해시 검증 | 소스와 이미지 동일성 확인 | SHA-256, 필요 시 SHA-512 병행 |
| 보관 체계 | 원본 봉인, 이미지 접근통제 | WORM, 접근로그, 보관기간 |

> 요약: 디스크 이미징 구조는 원본 보호, 사본 생성, 해시 검증, 보관 통제로 이루어진다.

---

## Ⅲ. 동작원리 및 흐름도

```text
증거 식별 -> 매체 정보 기록 -> 쓰기방지 연결 -> 비트스트림 이미징
-> SHA-256 산출 -> 원본/이미지 해시 대조 -> 사본 분석 -> 원본 봉인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 매체 모델, 일련번호, 용량, 인터페이스 기록 | 사진과 라벨 일치 |
| 2 | 하드웨어 쓰기방지 연결 및 인식 확인 | write block 테스트 로그 |
| 3 | RAW/E01 이미지 생성, 오류 섹터 기록 | 도구 로그와 완료 상태 |
| 4 | 원본·이미지 SHA-256 계산 및 대조 | 해시 100% 일치 |
| 5 | 분석 사본 생성 후 원본 봉인 | 봉인번호, 보관 위치 기록 |

> 요약: 이미징은 쓰기방지 후 비트 단위 복제와 SHA-256 대조를 거쳐 분석 사본으로 전환된다.

## Ⅳ. 특징

| 구분 | 일반 파일 복사 | 디스크 이미징·해시 무결성 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 복제 범위 | 보이는 파일 중심 | 삭제 영역, 슬랙, 메타데이터 포함 | 비트스트림 이미지 |
| 원본 보호 | 쓰기 발생 가능 | 하드웨어 쓰기방지 | write block 로그 |
| 검증 | 파일 개수 비교 | SHA-256 해시 대조 | 원본·이미지 100% 일치 |
| 오류 처리 | 실패 파일 누락 | 불량 섹터, HPA/DCO 기록 | 오류 섹터 목록 첨부 |

> 요약: 디스크 이미징은 일반 복사와 달리 비가시 영역까지 포함하고 해시값으로 동일성을 입증한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 파일 단위 수집 | 비트스트림 이미지 | 삭제 파일·메타데이터 필요 여부 |
| 비용/성능 | 빠른 복사 | 대용량 이미징 시간 소요 | 증거성 vs RTO 우선순위 |
| 운영/위험 | 원본 직접 분석 | 원본 봉인, 사본 분석 | 소송·수사 가능성 |

> 요약: 삭제 데이터와 증거능력이 필요하면 파일 복사보다 비트스트림 이미징을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 원본 변경 | OS 자동 마운트, 인덱싱 | 하드웨어 쓰기방지, 오프라인 획득 | 쓰기방지 테스트 로그 |
| 해시 불일치 | 불량 섹터, 중단된 획득 | 재시도, 오류 섹터 기록, 도구 교차검증 | 해시 일치율, 오류 목록 |
| 도구 신뢰성 | 검증되지 않은 이미저 | NIST CFTT 보고서, 내부 검증 이미지 | 검증 케이스 통과율 100% |

> 요약: 이미징 리스크는 원본 변경, 해시 불일치, 도구 오류이며 쓰기방지와 검증된 도구로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 무결성 | 원본·이미지 SHA-256 일치 | 해시 로그, 도구 리포트 |
| 원본 보호 | 쓰기 이벤트 0건 | write blocker 로그 |
| 획득 완전성 | 오류 섹터 목록 100% 기록 | 이미징 로그 검토 |
| 접근통제 | 이미지 열람자 로그 100% | WORM, DLP, 권한 로그 |

> 요약: 이미징 품질은 SHA-256 일치, 쓰기 이벤트 0건, 오류 기록, 접근로그로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 수집 전 매체 사진, 모델, 일련번호, 용량, 봉인번호를 기록하고 하드웨어 쓰기방지 장치 동작 로그를 확보한다.
2. RAW 또는 E01 형식으로 비트스트림 이미지를 생성하고 원본·이미지 SHA-256 해시를 대조해 보고서에 첨부한다.
3. 분석은 복제 이미지에서 수행하고 원본은 봉인 보관하며, 불량 섹터와 HPA/DCO 확인 결과를 체인 오브 커스터디에 남긴다.

**결론 (2줄):**
- 기술사 판단: 단순 로그 확인이면 파일 수집, 삭제영역·증거능력이 쟁점이면 디스크 이미징과 SHA-256 검증을 적용함
- 향후 방향: SSD TRIM, 클라우드 볼륨, 가상디스크 환경은 스냅샷 해시와 플랫폼 감사로그를 함께 검증함
