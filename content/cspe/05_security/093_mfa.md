## 미리 알고가기

- MFA는 서로 다른 인증 요소를 둘 이상 사용해 로그인 강도를 높이는 방식임
- 비밀번호와 비밀번호 재입력처럼 같은 종류를 반복하는 것은 엄밀한 MFA가 아님
- SMS OTP, TOTP, 푸시 승인, 보안키는 모두 2차 인증 수단이 될 수 있지만 피싱 저항성은 크게 다름

## Ⅰ. 개요

- **정의/개념**: MFA는 지식·소유·생체처럼 서로 다른 인증 요소를 조합해 단일 자격 증명 탈취만으로는 계정 접근이 어렵게 만드는 인증 체계임
- **배경/필요성**: 패스워드 재사용과 피싱과 크리덴셜 스터핑이 보편화되면서 비밀번호만으로는 핵심 서비스 보호가 어려워 추가 인증이 기본 요구로 자리잡음

## Ⅱ. 특징

- 단일 비밀번호 탈취의 피해를 크게 줄일 수 있음
- 2차 인증 방식에 따라 피싱 저항성과 운영 편의와 복구 난도가 달라짐
- 푸시 피로 공격과 SIM 스와핑처럼 MFA 자체를 노리는 공격도 존재함
- 모든 화면에 동일 강도를 강제하기보다 위험 기반으로 단계 적용하는 것이 효과적임

## Ⅲ. 종류 및 비교

| 판단 기준 | SMS/TOTP 기반 MFA | FIDO 기반 피싱 저항 MFA |
|:---|:---|:---|
| 사용자 경험 | 배포가 쉽고 익숙함 | 초기 등록은 필요하지만 로그인은 간편함 |
| 강점 | 도입 장벽이 낮음 | 피싱과 중간자 공격 저항성이 높음 |
| 한계 | 코드 탈취와 푸시 피로 공격 위험 | 기기 호환성과 등록 정책 설계 필요 |
| 적합 환경 | 일반 서비스의 단계적 강화 | 관리자 계정, 중요 시스템, 고위험 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 1차 인증 | 비밀번호나 기본 신원 검증을 수행함 |
| 추가 요소 | OTP, 푸시, 보안키, 생체 등으로 2차 확인함 |
| 위험 평가 | 위치, 기기, 시간, 행위를 바탕으로 추가 인증 여부를 조정함 |
| 복구 절차 | 기기 분실과 실패 상황을 처리함 |

```text
기본 로그인 -> 위험 평가 -> 추가 인증 요구 -> 성공 시 세션 발급 -> 복구/예외 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
1차 인증 -> 컨텍스트 평가 -> 2차 인증 -> 접근 허용 -> 이상 징후 재점검
```

1. **1차 인증**: 기본 자격 증명을 확인함
2. **컨텍스트 평가**: 접속 위치와 기기와 행위를 분석함
3. **2차 인증**: 필요한 추가 요소를 검증함
4. **접근 허용**: 성공 시 세션을 발급함
5. **재점검**: 실패 패턴과 피로 공격 징후를 모니터링함

## Ⅵ. 실무 적용 및 유의점

1. 관리자 계정과 원격 접속 계정은 MFA를 기본 요구로 두고, SMS보다 보안키나 FIDO 기반 방식을 먼저 적용한 뒤 피싱 기반 계정 탈취 감소와 예외 계정 축소 여부로 확인함
2. 사용자 서비스는 강한 MFA를 일괄 강제하기보다 위험 기반 요구와 복구 절차를 함께 설계하고 이탈률과 인증 성공률과 푸시 피로 공격 탐지 건수로 확인함

## Ⅶ. 결론

- MFA는 추가 인증 한 번 붙이는 기능이 아니라 어떤 요소를 어떤 계정과 상황에 적용할지 설계하는 운영 체계여야 함
