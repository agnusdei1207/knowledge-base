## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 지식·소유·생체 중 2개 이상의 서로 다른 인증 요소를 조합하여 사용자 신원을 검증하는 인증 방식임 |
| **배경/필요성** | 단일 패스워드 인증의 피싱·크레덴셜 스터핑 취약점을 보완하기 위해 추가 인증 요소가 필수적임 |
| **출제 의도** | MFA의 구성 요소 조합과 피싱 저항 MFA(FIDO2)의 차이를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 1차요소   | --> | 2차요소   | --> | 적응형   |
| (PW/PIN) |     | (OTP/Push)|     | 리스크평가|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 1차 요소 | 패스워드·PIN 등 지식 기반 인증으로 기본 신원을 확인함 | 현관문 비밀번호 |
| 2차 요소 | TOTP·SMS OTP·인증 앱 푸시 등 소유 기반으로 추가 검증함 | 현관문 안쪽 체인 잠금장치 |
| 적응형 MFA | 접속 위치·디바이스·행위 패턴에 따라 인증 강도를 동적 조절함 | 수상한 방문자에게 추가 질문 |

> 요약: 서로 다른 인증 요소를 조합하고, 리스크에 따라 인증 강도를 동적 조절하는 체계임.

## Ⅲ. 절차
```
+------------+     +------------+
| ID/PW입력  | --> | 리스크평가  |
| (1차인증)  |     | (위치·장치)|
+------------+     +------------+
                        |
+------------+     +----+-------+
| 접근허가   | <-- | 2차인증   |
|            |     | (OTP/Push)|
+------------+     +------------+
```

1. 1차 인증: 사용자가 ID와 패스워드를 입력하여 기본 자격증명을 제출함
2. 리스크 평가: 접속 IP·디바이스·시간대 등 컨텍스트를 분석하여 위험 수준을 판단함
3. 2차 인증 요구: 고위험으로 판단 시 OTP·인증 앱 푸시·생체 인증을 추가 요구함
4. 접근 허가: 모든 요소를 충족한 경우에만 세션을 발급하고 리소스 접근을 허용함

> 요약: 1차 인증 → 리스크 평가 → 2차 인증 → 접근 허가로 적응형 MFA를 수행함.

## Ⅳ. 문제점
- SMS OTP 취약: SIM 스와핑·SS7 프로토콜 공격으로 SMS OTP가 탈취될 수 있음
- MFA 피로 공격: 인증 앱 푸시를 반복 발송하여 사용자가 실수로 승인하도록 유도함
- 사용자 경험 저하: 매 접속 시 추가 인증이 요구되면 업무 생산성이 감소함

## Ⅴ. 개선방안
- (단기) 번호 매칭: 인증 앱에 번호 매칭(Number Matching)을 적용하여 MFA 피로 공격을 차단함
- (중기) FIDO2 전환: 피싱 저항 MFA인 FIDO2/WebAuthn으로 SMS·TOTP를 대체함
- (장기) 연속 인증: 세션 중 행위 분석 기반 연속 인증으로 명시적 2차 인증 빈도를 줄임

## Ⅵ. 전망
- MS·Google·Apple이 패스키(FIDO2)를 기본 지원하면서 피싱 저항 MFA가 표준화되며, 적응형·연속 인증으로 사용자 경험과 보안을 동시에 달성하는 방향으로 발전할 전망임
