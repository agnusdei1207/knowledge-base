## 미리 알고가기

- SRI는 외부 CDN에서 내려받는 스크립트나 스타일 파일의 해시값을 HTML에 적어 두고 브라우저가 실제 파일과 비교하게 하는 방식임
- 목적은 외부 리소스가 변조됐을 때 브라우저가 실행을 막게 하는 데 있음
- CSP가 출처를 제한한다면 SRI는 내려받은 파일 내용의 무결성을 확인하는 역할임

## Ⅰ. 개요

- **정의/개념**: SRI는 외부 JavaScript·CSS 리소스의 예상 해시값을 선언해 브라우저가 파일 무결성을 검증하고 불일치 시 차단하는 기법임
- **배경/필요성**: CDN이나 공급망이 침해되면 정상 URL에서 악성 스크립트가 배포될 수 있음. 출처뿐 아니라 파일 내용 검증이 필요함

## Ⅱ. 특징

- 외부 CDN을 계속 쓰면서 변조 탐지 장치를 추가함
- 정적 리소스에 적합하며 파일이 자주 바뀌면 해시 관리 부담이 커짐
- 리소스 내용이 조금만 달라도 차단되므로 배포 자동화가 필요함
- SRI만으로 DOM 기반 XSS나 내부 스크립트 문제를 막을 수 없음

## Ⅲ. 종류 및 비교

| 판단 기준 | CSP | SRI |
|:---|:---|:---|
| 주된 목적 | 어떤 출처를 허용할지 제한 | 내려받은 파일 내용이 변조됐는지 확인 |
| 적용 대상 | 스크립트, 스타일, 네트워크 요청 등 정책 전반 | 외부 스크립트와 스타일 리소스 |
| 강점 | 실행 범위를 넓게 통제 | CDN 변조를 직접 탐지 |
| 한계 | 허용된 출처 내 변조는 별도 확인 못 함 | 허용 출처 자체 제한 기능은 없음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| integrity 속성 | 예상 해시값을 태그에 기록함 |
| 리소스 요청 | 브라우저가 외부 파일을 가져옴 |
| 해시 비교 | 실제 파일 해시와 선언값을 대조함 |
| 차단 또는 실행 | 일치하면 실행하고 불일치면 차단함 |

```text
HTML에 해시 선언 -> 외부 리소스 다운로드 -> 브라우저 해시 계산 -> 비교 -> 실행/차단
```

## Ⅴ. 원리 및 절차 흐름도

```text
리소스 해시 생성 -> 태그에 삽입 -> 배포 -> 브라우저 검증 -> 불일치 차단 -> 해시 갱신 관리
```

1. **해시 생성**: 배포할 파일의 해시를 계산함
2. **태그 삽입**: `integrity` 속성에 해시를 기록함
3. **배포**: HTML과 외부 리소스를 함께 배포함
4. **브라우저 검증**: 다운로드한 파일과 해시를 비교함
5. **갱신 관리**: 파일 버전이 바뀌면 새 해시를 반영함

## Ⅵ. 실무 적용 및 유의점

1. 외부 CDN 스크립트·스타일은 SRI를 기본 적용하고 해시 갱신을 빌드 자동화에 묶어 SRI 적용률·변조 차단 재현으로 확인함
2. 자주 갱신되는 자산은 버전 고정과 배포 순서를 관리하고 해시 갱신 누락 건수·차단 운영 영향으로 확인함

## Ⅶ. 결론

- SRI는 외부 리소스의 실제 내용 무결성을 검증하는 장치이므로 CDN 의존 서비스에서 CSP와 함께 써야 함
