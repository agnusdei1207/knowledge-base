## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 외부 CDN에서 로드하는 스크립트·스타일시트의 해시값을 HTML 태그에 명시하여, 변조된 리소스 실행을 브라우저가 차단하는 무결성 검증 기법임 |
| **배경/필요성** | CDN 해킹·공급망 공격으로 정상 라이브러리에 악성 코드가 삽입되는 사건(Magecart 등)이 빈발하여, 로딩 시점의 무결성 검증이 필수임 |
| **출제 의도** | SRI의 동작 원리와 CDN 공급망 보안에서의 역할을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| integrity| --> | 해시비교  | --> | 실행허가  |
| 속성     |     | (SHA-384)|     | /차단    |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| integrity 속성 | `<script>` 태그에 `integrity="sha384-..."` 형태로 예상 해시값을 명시함 | 택배 봉인 스티커 번호 |
| crossorigin 속성 | CORS 요청으로 외부 리소스를 가져올 때 필요한 출처 정책을 설정함 | 국제 택배 통관 서류 |
| 해시 비교 | 브라우저가 다운로드한 리소스의 해시를 계산하여 명시된 값과 대조함 | 봉인 번호 검증 |

> 요약: HTML 태그의 해시값과 다운로드된 리소스의 실제 해시를 비교하여 변조를 탐지·차단함.

## Ⅲ. 절차
```
+------------+     +------------+
| HTML파싱   | --> | CDN에서   |
| integrity  |     | 리소스다운 |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 실행허가   | <-- | 해시계산  |
| 또는차단   |     | 및 비교   |
+------------+     +------------+
```

1. 해시 명시: 개발자가 빌드 시 리소스의 SHA-384 해시를 계산하여 `integrity` 속성에 기록함
2. 리소스 다운로드: 브라우저가 CDN에서 스크립트·CSS 파일을 다운로드함
3. 해시 비교: 다운로드된 파일의 해시를 계산하여 `integrity` 속성 값과 대조함
4. 실행 결정: 해시 일치 시 실행을 허용하고, 불일치 시 리소스 로딩을 차단하여 변조를 방지함

> 요약: 해시 명시 → 다운로드 → 해시 비교 → 실행/차단으로 CDN 리소스 변조를 방어함.

## Ⅳ. 문제점
- 동적 리소스 미지원: 버전이 수시로 변경되는 리소스는 해시값 갱신 관리가 어려움
- 적용 범위 한계: `<script>`, `<link>` 태그만 지원하며 `fetch()`·`XMLHttpRequest`는 미지원임
- CDN 장애 시 폴백: SRI 실패 시 리소스가 차단되어 서비스 가용성에 영향을 줄 수 있음

## Ⅴ. 개선방안
- (단기) 빌드 자동화: CI/CD 파이프라인에서 SRI 해시를 자동 생성·삽입하여 관리 부담을 제거함
- (중기) 폴백 전략: SRI 실패 시 자체 호스팅 리소스로 자동 전환하는 폴백 로직을 구현함
- (장기) Trusted Types 연계: CSP Trusted Types와 SRI를 조합하여 DOM 기반 XSS까지 통합 방어함

## Ⅵ. 전망
- npm·CDN 공급망 공격 증가에 따라 SRI 적용이 보안 컴플라이언스 필수 항목으로 격상되며, Import Maps와의 연동이 표준화될 전망임
