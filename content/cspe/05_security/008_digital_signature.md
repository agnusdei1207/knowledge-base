## 미리 알고가기

- 서명 생성: 메시지 해시값을 개인키로 처리해 서명값을 만드는 절차임
- 서명 검증: 공개키로 서명값과 메시지 해시의 관계를 확인하는 절차임
- 부인방지: 서명자가 사후에 서명 사실을 부정하기 어렵게 하는 성질임
- 인증서: 공개키와 서명자 신원을 연결하는 전자 문서임
- 타임스탬프: 특정 시점에 서명 또는 문서가 존재했음을 확인하는 값임

## Ⅰ. 개요

- **정의/개념**: 전자 서명은 개인키로 생성한 서명값을 공개키로 검증해 메시지 무결성과 서명자 신원을 확인하는 기술임
- **배경/필요성**: 비대면 문서, 코드, 인증서 발급에서는 데이터 변경 여부와 작성 주체를 함께 검증해야 함

## Ⅱ. 특징

- 서명 생성 권한은 개인키 보유자에게 집중됨
- 검증은 공개키로 수행되므로 제3자 검증이 가능함
- 원문 전체가 아니라 원문 해시값을 서명 대상으로 삼는 경우가 일반적임
- 서명자 신원은 공개키 자체가 아니라 인증서 검증으로 확인함

## Ⅲ. 종류 및 비교

| 구분 | RSA 서명 | ECDSA | ML-DSA |
|:---|:---|:---|:---|
| 기반 | 소인수분해 | 타원곡선 이산대수 | 격자 기반 난제 |
| 장점 | 레거시 호환성 | 짧은 키·서명 | PQC 전환 대상 |
| 주요 위험 | 긴 키와 서명 크기 | Nonce 재사용 | 인증서 생태계 전환 |
| 적용 판단 | 기존 PKI | TLS·모바일 인증 | 장기 양자 대응 |

> 요약: 서명 알고리즘 선택은 검증 생태계, 키 관리, 장기 안전성 요구로 판단함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 원문 | 서명 대상 데이터 |
| 해시 함수 | 원문을 고정 길이 입력으로 축약 |
| 개인키 | 서명 생성에 사용 |
| 공개키 | 서명 검증에 사용 |
| 인증서 | 공개키와 주체 식별 정보 연결 |

```text
원문 -> 해시 -> 개인키 서명 -> 서명값
원문 -> 해시 + 서명값 + 공개키 -> 검증 결과
```

## Ⅴ. 원리 및 절차 흐름도

1. **문서 확정**: 서명할 원문과 인코딩 방식을 고정함
2. **해시 계산**: 원문 다이제스트를 생성함
3. **서명 생성**: 개인키로 알고리즘별 서명값을 만듦
4. **서명 전달**: 원문, 서명값, 인증서 체인을 함께 제공함
5. **서명 검증**: 공개키, 해시값, 인증서 상태를 함께 확인함

## Ⅵ. 실무 적용 및 유의점

- 코드 서명은 배포 파일 변조와 배포 주체를 함께 검증함
- 전자문서 서명은 인증서 폐지 상태와 서명 시점을 함께 보관해야 함
- 개인키가 유출되면 과거·미래 서명 신뢰 판단에 영향을 줌
- 서명 검증은 알고리즘 검증뿐 아니라 인증서 체인 검증을 포함함
- 장기 보존 문서는 타임스탬프와 알고리즘 교체 계획이 필요함

## Ⅶ. 결론

- 전자 서명은 암호화가 아니라 무결성, 서명자 확인, 부인방지를 위한 공개키 응용임
- 답안에서는 개인키 서명과 공개키 검증 절차, 인증서 신뢰 경로를 함께 제시해야 함

## 작성 근거(검토용)

- 서명을 “암호화”로 설명하는 오류를 막기 위해 생성·검증 절차를 분리함
- 부인방지는 인증서와 키 관리 조건이 있을 때 의미가 있으므로 조건을 명시함
- RSA, ECDSA, ML-DSA 비교로 레거시와 PQC 전환 판단을 연결함
