# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 비대칭 암호화를 응용하여 데이터의 **작성자 신원(인증)**, **내용 변조 여부(무결성)**, **사후 부인 방지(부인방지)**를 보장하는 기술.
- **왜 필요한가**: 디지털 데이터는 복제와 수정이 너무 쉬움. 전자 서명은 현실 세계의 인감도장이나 서명처럼 디지털 데이터에 법적·기술적 효력을 부여함.
- **핵심 직관**: **"데이터에 찍는 인감도장"**. 나만 가진 도장(개인키)으로 찍고, 누구나 인감증명서(공개키)로 확인할 수 있지만, 도장을 위조하는 것은 불가능함.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| **서명 (Signing)** | 개인키로 메시지의 해시값을 암호화하는 과정 | 서류에 직접 도장을 찍는 행위 |
| **검증 (Verification)** | 공개키로 서명값을 복호화하여 해시값을 대조하는 과정 | 인감증명서와 도장을 대조해보는 행위 |
| **부인 방지** | Non-repudiation. 서명자가 나중에 "내가 안 했다"고 거짓말하는 것을 막음 | 지장이 찍힌 계약서를 들이밀며 증명하는 것 |
| **RSA-PSS** | RSA 기반의 안전한 패딩 서명 방식 | 도장을 찍을 때 주변에 복잡한 무늬를 넣어 위조를 막는 방식 |
| **EdDSA** | 타원 곡선 기반의 고속/안전 서명 방식 | 매우 정교하고 빠르게 찍히는 최신식 디지털 인감 |

## 깊이 이해
- **동작 프로세스 (중요)**:
  1. **해싱**: 메시지 $M$을 해시 함수에 넣어 다이제스트 $H(M)$ 생성. (본문 전체를 암호화하면 너무 느리기 때문)
  2. **서명**: 생성된 $H(M)$을 송신자의 **개인키($SK$)**로 암호화하여 서명값 $S$ 생성.
  3. **전송**: 메시지 $M$과 서명 $S$를 함께 수신자에게 보냄.
  4. **검증**: 수신자는 $M$을 직접 해싱하여 $H(M)$을 얻고, 동시에 송신자의 **공개키($PK$)**로 $S$를 복호화하여 결과값을 비교. 일치하면 신뢰.
- **HMAC과의 차별점**:
  - HMAC은 공유키 방식이라 "둘 중 누가 보냈는지" 제3자에게 증명할 수 없음.
  - 전자 서명은 개인키가 유일하므로 **제3자 앞에서도 부인 방지**가 가능함.
- **양자 위협**:
  - RSA/ECDSA 서명은 양자 컴퓨터에 의해 무력화될 수 있음.
  - **대응**: 격자 기반 암호인 **ML-DSA (Crystals-Dilithium)**가 차세대 표준으로 선정됨.

## 연결 개념
- **004 해시**: 서명 전 데이터를 압축하는 엔진.
- **009 PKI**: 공개키가 정말 그 사람의 것인지 보증해주는 인프라.
- **111 VC (Verifiable Credential)**: 전자 서명을 기반으로 한 탈중앙화 신원 증명.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 해시 함수와 비대칭 암호화를 결합하여 데이터의 **인증, 무결성, 부인방지**를 제공하는 공개키 응용 기술임.
> 2. **가치**: 전자상거래, 전자계약, 코드 서명(Code Signing), 블록체인 트랜잭션의 신뢰 구축을 위한 핵심 근거임.
> 3. **판단 포인트**: 기밀성(Confidentiality)은 제공하지 않으므로 암호화와 병행해야 하며, **개인키의 안전한 보관(HSM)**이 전체 신뢰의 전제 조건임.

## 출제 의도 및 답안 포인트
- **출제 의도**: 전자 서명의 3대 보안 속성 이해와 해시-비대칭키 결합 프로세스 숙달 여부 확인.
- **감점 회피**: **부인 방지(Non-repudiation)** 개념을 명확히 정의하고, **기밀성은 제공하지 않는다**는 점을 반드시 명시할 것.

---

## Ⅰ. 디지털 신뢰의 법적·기술적 근거, 전자 서명의 개요
### 1. 정의 및 개념
- 송신자의 개인키로 메시지의 해시값을 암호화하여 데이터와 함께 전송하는 기술
- 수신자가 송신자의 공개키로 서명을 검증하여 데이터의 진위 파악

### 2. 전자 서명의 3대 보안 요구사항
- **인증 (Authentication)**: 서명자가 누구인지 확인 가능.
- **무결성 (Integrity)**: 서명 후 데이터가 변경되지 않았음을 보장.
- **부인방지 (Non-repudiation)**: 서명 사실을 사후에 부인할 수 없음.

---

## Ⅱ. 전자 서명의 메커니즘 및 동작 절차
### 1. 서명 생성 및 검증 프로세스
```text
[송신자]  메시지(M) -> Hash -> 다이제스트 -> 개인키(SK)로 암호화 -> 서명(S) 생성
[전송]    (M, S) 전송
[수신자]  M -> Hash -> 다이제스트(A)
          S -> 공개키(PK)로 복호화 -> 다이제스트(B)
          비교 (A == B) -> 검증 완료
```

### 2. 주요 알고리즘 비교
| 구분 | RSA-PSS | ECDSA | EdDSA (Ed25519) |
|:---|:---|:---|:---|
| **기반 난제** | 소인수분해 | 타원곡선 이산로그 | 타원곡선 (Edwards Curve) |
| **서명 크기** | 큼 (2048~4096 bit) | 작음 (512 bit) | 매우 작음 (512 bit) |
| **보안성** | 검증된 안전성 | Nonce 재사용에 취약 | **결정적 서명** (매우 안전) |
| **용도** | 일반 인증서, 문서 | 비트코인, TLS | 고속 API, IoT, 신규 프로토콜 |

---

## Ⅲ. 전자 서명의 실무적 활용 사례
### 1. 소프트웨어 코드 서명 (Code Signing)
- 배포되는 실행 파일이 공식 개발사에 의해 제작되었고 변조되지 않았음을 OS가 검증.

### 2. 전자 봉투 (Digital Envelope)
- 기밀성이 필요한 경우: (본문 암호화 대칭키)를 수신자 공개키로 암호화 + (본문 해시)를 송신자 개인키로 서명.

### 3. 블록체인 및 가상자산
- 트랜잭션의 소유권을 증명하기 위해 ECDSA 또는 Schnorr 서명 활용.

---

## Ⅳ. 보안 위협 및 대응 전략
### 1. 개인키 탈취 위협
- **위협**: 개인키가 유출되면 공격자가 서명자를 사칭하여 허위 서명 생성 가능.
- **대응**: **HSM(Hardware Security Module)** 또는 **TPM** 내에 키를 저장하여 물리적 추출 방지.

### 2. 인증서 유효성 리스크
- **위협**: 서명이 유효하더라도 기반 인증서가 폐지되었을 수 있음.
- **대응**: **OCSP (Online Certificate Status Protocol)** 또는 **CRL** 실시간 조회 연동.

---

## Ⅴ. 미래 기술: 양자 내성 서명 (ML-DSA)
- **NIST 표준**: CRYSTALS-Dilithium (ML-DSA) 선정.
- **특징**: 격자 기반 암호를 사용하여 양자 컴퓨터의 Shor 알고리즘 공격에 견딜 수 있도록 설계됨.
- **전환**: 기존 ECDSA/RSA 서명과 ML-DSA 서명을 병합하는 하이브리드 서명 도입 가속화.

---

## Ⅵ. 실무적 제언 및 결론
### 1. 시스템 설계 시 고려사항
- 성능이 중요한 대량 API 인증에는 **HMAC**을, 법적 증거력이 필요한 중요한 계약에는 **전자 서명**을 선택하는 적재적소의 설계 필요.
- 서명 시각의 무결성을 위해 **TSA (Time Stamping Authority)** 연동 권고.

### 2. 결론
- 전자 서명은 단순 기술을 넘어 디지털 경제의 **'신뢰 인프라'**임.
- 양자 시대로의 전환기(Migration)를 맞이하여 알고리즘의 유연성(Agility)을 확보하는 것이 차세대 보안 시스템의 핵심 과제임.

### 🔀 문제 유형별 목차 전환
| 유형 | Ⅱ·Ⅲ 강조 (원리 중심) | Ⅴ·Ⅵ 강조 (전략 중심) |
|:---|:---|:---|
| **프로세스 분석** | 해시-암호화 연동 수식, 검증 로직 상세 | 알고리즘별 서명/검증 속도 비교, 오버헤드 분석 |
| **법규/거버넌스** | 전자서명법상의 효력, 부인방지의 증거력 | PKI 거버넌스 체계, PQC 서명 전환 로드맵 |
