## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 비대칭키(공개키) 암호화 기술과 해시 함수를 결합하여, 디지털 문서의 출처를 증명하고 위변조되지 않았음을 보증하는 암호학적 도장(인감)입니다.
- **필요성**: 디지털 세상의 파일은 복사나 조작이 너무 쉬워서, "이 계약서를 앨리스가 직접 썼다"거나 "중간에 내용이 바뀌지 않았다"는 것을 법적·기술적으로 증명해야 합니다.
- **핵심 직관**: **"나만 찍을 수 있는 도장, 누구나 진품 확인 가능한 돋보기"**. 앨리스는 자신만 가진 인감도장(개인키)으로 문서에 도장을 찍습니다. 이 도장이 진짜 앨리스의 것인지 확인하고 싶은 밥은, 동사무소에 등록된 앨리스의 인감증명서(공개키)라는 돋보기를 가져와 도장의 진위를 확인합니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 종이 문서의 수기 서명이나 인감도장은 디지털 환경에 적용할 수 없습니다(단순 이미지 복사 가능). 이를 수학적으로 해결하기 위해 공개키 암호학의 '서명/인증' 특성을 활용하게 되었습니다.
- **가치**: 전자상거래, 전자계약, 인터넷 뱅킹, 암호화폐 전송 등 "내가 했다"는 책임을 증명해야 하는 모든 행위의 근간 기술입니다. **부인방지(Non-repudiation)** 를 제공하는 유일한 기술적 수단입니다.

## 3. 어떻게 작동하는가? (Mechanism)
- **작동 원리 (Step-by-Step)**:
  1. **해시 추출**: 송신자(Alice)는 전송할 문서(M) 전체를 암호화하기엔 너무 무거우므로, 해시 함수에 넣어 짧은 '해시값(H)'을 만듭니다. (문서의 지문 역할)
  2. **서명 생성 (개인키로 암호화)**: 앨리스는 자신의 **개인키(Private Key)** 를 사용해 추출된 해시값을 암호화합니다. 이것이 바로 '전자서명(S)'입니다.
  3. **전송**: 원본 문서(M)와 만들어진 전자서명(S)을 함께 밥에게 보냅니다.
  4. **서명 검증 (공개키로 복호화)**: 수신자(Bob)는 앨리스의 **공개키(Public Key)** 로 전자서명(S)을 복호화합니다. 복호화에 성공하면 서명 속에서 '해시값(H)'이 나옵니다.
  5. **무결성 확인**: 밥은 전달받은 원본 문서(M)를 직접 해시 함수에 돌려 자신만의 '해시값(H')'을 구합니다. 그리고 4번에서 나온 H와 H'이 **완전히 일치하는지 비교**합니다. 일치하면 서명이 유효합니다.

```ascii
[ 송신자 (Alice) ]                                  [ 수신자 (Bob) ]

 문서 (M) ─────▶ [ 해시 함수 ] ────▶ 해시(H)         문서 (M) ─────▶ [ 해시 함수 ] ─────▶ 해시(H')
   │                                   │              │                                     │
   │                              [ Alice 개인키 ]    │                                     │
   │                                   ▼              │                                     ▼
   │                               [ 암호화 ]         │                               [ 비교/검증 ]
   │                                   │              │                                     ▲
   │                                   ▼              │                                     │
   └────────── (네트워크 전송) ─────────┼─────────────┘                                [ 복호화 ]
                                 전자 서명(S) ───────────────────────────────────────────▶ │
                                                                                      [ Alice 공개키 ]
```

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례**: 
  - **공동인증서 (NPKI)**: 국세청 연말정산이나 은행 송금 시, 내 PC의 `SignKorea` 등 인증서 폴더에 있는 **개인키**를 불러와 거래 내역에 서명을 생성하여 서버로 보냅니다.
  - **소프트웨어 코드 사이닝**: 앱스토어나 윈도우에서 프로그램을 다운받아 실행할 때 "게시자: Microsoft Corporation"처럼 뜨는 것은, MS가 자신의 개인키로 실행파일에 전자서명을 해두었기 때문입니다.
- **주의점 및 흔한 오해**: 
  - 전자서명 자체는 **문서를 암호화(숨기기)하지 않습니다**. 원본 문서와 서명이 같이 날아가므로 누구나 내용은 볼 수 있습니다. 기밀성이 필요하면 전자서명 후 별도의 하이브리드 암호화(전자봉투)를 해야 합니다.
  - "이 공개키가 진짜 앨리스 것이 맞나?"라는 근본적 의문을 해결하기 위해 공인된 제3자(CA)가 개입하는 **PKI(공개키 기반 구조)** 인프라가 반드시 뒷받침되어야 합니다.

## 5. 핵심 비교 및 연결 개념 (Relation)
- **VS HMAC**: HMAC은 대칭키를 쓰므로 '부인방지(발뺌 방지)'가 안 됩니다. 전자서명은 개인키가 앨리스에게만 있으므로 발뺌이 불가능합니다(법적 효력).
- **연결 개념**: 
  - **블라인드 서명 (Blind Signature)**: 문서 내용을 서명자(예: 선관위, 은행)에게 숨긴 채 도장만 받아내는 기술 (전자투표, 익명 디지털 화폐).

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 해시(Hash) 함수의 무결성 특성과 비대칭키 암호(Asymmetric Crypto)의 기밀/인증 특성을 결합한 **암호학적 인증 메커니즘**.
- **가치**: 정보보호의 핵심 목표 중 인증(Authentication), 무결성(Integrity), **부인방지(Non-repudiation)** 의 3가지 요소를 단일 메커니즘으로 완벽히 보장하여 전자 상거래의 법적 기반을 제공함.
- **판단 포인트**: 연산 효율성을 위해 문서 전체가 아닌 $Hash(M)$에 서명하는 Hash-then-Sign 패러다임이 필수적이며, 서명의 신뢰성을 보장할 PKI 체계와의 통합이 핵심 아키텍처임.

### Ⅱ. 전자서명의 암호학적 요구조건 및 성질
1. **위조 불가 (Unforgeability)**: 정당한 서명자(개인키 소유자) 이외에는 올바른 서명을 생성할 수 없어야 함.
2. **인증 / 신원 확인 (Authentication)**: 서명을 통해 송신자가 누구인지(공개키 대응) 명확히 입증할 수 있어야 함.
3. **부인 방지 (Non-repudiation)**: 서명자가 나중에 "내가 서명하지 않았다"고 부정할 수 없도록 법적/수학적 강제력을 가짐.
4. **변경 불가 / 무결성 (Integrity)**: 서명된 문서는 전송 도중 단 1비트의 조작도 서명 검증 과정에서 탐지되어야 함 (해시 눈사태 효과).
5. **재사용 불가 (Non-reusability)**: 한 문서의 서명을 떼어내어 다른 문서의 서명으로 재활용할 수 없어야 함 ($Sig=E_{PR}(Hash(M))$이므로 문서마다 값이 고유함).

### Ⅲ. 전자서명 생성 및 검증 메커니즘 수식화
- **서명 생성 (Sign Generation)**
  - 송신자 A: $S = E_{PR_A}(H(M))$ (자신의 개인키 $PR_A$ 사용)
  - 전송 데이터 포맷: $M\ ||\ S$
- **서명 검증 (Sign Verification)**
  - 수신자 B: 서명 복호화 $H' = D_{PU_A}(S)$ (송신자 A의 공개키 $PU_A$ 사용)
  - 메시지 해싱: $H'' = H(M)$
  - 결과 비교: $H' == H''$ 이면 인증 완료 및 무결성 보장.

### Ⅳ. 핵심 알고리즘 및 표준
1. **RSA 서명**: 가장 전통적이고 널리 쓰이는 방식. 패딩 방식에 따라 보안성이 달라지며, 현재는 구조적 결함 방지를 위해 **RSA-PSS (Probabilistic Signature Scheme)** 패딩이 표준으로 사용됨.
2. **DSA (Digital Signature Algorithm)**: 미국 NIST가 발표한 FIPS 186 표준. 이산대수 문제(DLP) 기반이며, 서명 생성 시 임의의 난수($k$)가 필요함. 암호화 기능은 없고 오직 서명 기능만 제공.
3. **ECDSA (Elliptic Curve DSA)**: DSA를 타원곡선 상으로 옮긴 형태. 서명 속도가 빠르고 데이터 크기가 작아 비트코인 등 블록체인 트랜잭션 서명, 모바일/IoT 환경의 지배적 표준.

### Ⅴ. 특수 목적 전자서명 (Advanced Signatures)
- **블라인드 서명 (Blind Signature)**: 은닉 서명. 내용(M)을 블라인딩 인자로 가린 후 서명자에게 서명을 받고, 나중에 가림막을 벗겨내어 유효한 서명을 획득하는 기법. 추적 불가성(Untraceability) 제공. $\rightarrow$ 전자투표, CBDC(디지털 화폐)
- **다중 서명 (Multi-Signature / Multisig)**: 하나의 문서나 트랜잭션에 대해 N명 중 M명 이상의 서명이 모여야만 승인되는 형태. $\rightarrow$ 기업 결재 시스템, 가상자산 지갑 보안.
- **링 서명 (Ring Signature)**: 특정 그룹 내의 누군가가 서명했음은 검증되나, 서명자가 정확히 누구인지는 특정할 수 없는 익명성 서명 기법. $\rightarrow$ Monero(모네로) 등 다크코인 익명성 보장.

### Ⅵ. 결론 및 실무적 판단 포인트
- **서명 알고리즘 마이그레이션**: RSA 기반의 구형 서명 시스템은 점진적으로 **ECDSA 기반(P-256 이상)** 으로 전환하여 모바일 성능과 대역폭 효율을 최적화해야 함.
- **양자 컴퓨터 대비(PQC)**: 양자 알고리즘에 의해 RSA/ECDSA가 붕괴될 위험이 현실화됨. 따라서 차세대 시스템 설계 시 NIST PQC 표준인 **ML-DSA (구 Dilithium)** 또는 **SLH-DSA (구 SPHINCS+)** 같은 양자 내성 해시/격자 기반 전자서명 도입 로드맵을 구성해야 함.

### 💡 문제 유형별 목차 전환 포인트
- **[공동인증서(NPKI) 작동 원리 묻는 유형]**: Ⅲ번 항목을 구체화하여 공인인증서(개인키) 저장 위치, 비밀번호(Passphrase) 입력에 의한 암호화된 개인키 복호화 과정을 추가 서술.
- **[전자투표/익명성 요구 시스템 설계]**: Ⅴ번 항목의 블라인드 서명을 메인으로 끌어올려 Chaum의 블라인드 서명 알고리즘 원리(Blinding $\rightarrow$ Signing $\rightarrow$ Unblinding)를 도식화와 함께 심층 전개.
