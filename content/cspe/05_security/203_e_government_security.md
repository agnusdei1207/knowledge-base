# 📖 【암기용】 개념 완전 이해

> 목적: 전자정부 보안 요건을 처음 봐도 행정 정보시스템 구축·운영 보안의 흐름을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 전자정부 정보시스템과 행정정보를 보호하는 법·절차·기술 통제
- **왜 필요한가**: 전자문서, 행정정보 공동이용, 민원 서비스, 내부 행정망은 국민 신원·자격·재산 정보와 연결되어 무단 접근과 위변조를 막아야 한다.
- **핵심 직관**: 전자정부 보안은 운영 후 점검이 아니라, 정보화사업 계획 단계부터 보안성 검토와 접근통제를 설계에 넣는 방식임.

## 깊이 이해
- **배경·문제의식**: 전자정부 서비스는 여러 기관의 정보시스템과 행정정보를 연결한다. 하나의 인증 우회, 로그 누락, 암호화 누락이 기관 간 공동이용망 전체의 신뢰를 훼손할 수 있음.
- **작동 원리**: 사업 계획 단계에서 보안대책을 반영하고, 보안성 검토로 설계 위험을 확인한다. 구축·운영 단계에서는 인증, 접근통제, 암호화, 로그·감사, 개인정보 보호, 행정정보 이용 통제를 적용한다.
- **비유**: 청사 출입증을 나중에 붙이는 것이 아니라, 설계도 단계에서 출입구, CCTV, 기록 보관실, 비상대응 절차를 함께 배치하는 것과 같음.
- **구체 예시**: 행정정보 공동이용 시스템은 사용자 인증, 업무권한 기반 조회, TLS 1.3 전송암호화, DB 암호화, 원문 조회 로그 1년 이상 보관, 이상조회 탐지를 적용함.
- **흔한 오해·주의점**: 전자정부 보안은 웹 방화벽 설치 하나로 끝나지 않는다. 법·사업관리·보안성 검토·운영 감사가 연결된 공공 정보시스템 통제임.

## 연결 개념
- 보안성 검토 - 정보화사업 설계 단계의 보안 요구사항 사전 확인
- 행정정보 보호 - 공동이용, 접근권한, 위변조 방지, 로그감사
- 전자정부 정보시스템 등급관리 - 영향도 기반 점검과 관리 기준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 전자정부 보안 답안은 기술 장비 나열이 아니라 사업 계획, 보안성 검토, 행정정보 보호, 운영 감사의 흐름을 보여줘야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 전자정부법 보안 요건은 행정기관 정보시스템과 행정정보의 무단 접근, 위변조, 유출, 서비스 중단을 예방하는 관리·기술 통제 체계임.
> 2. **가치**: 전자문서, 공동이용, 민원 서비스가 신뢰 가능한 행정 행위로 성립하도록 인증, 접근통제, 로그, 암호화, 보안성 검토를 결합함.
> 3. **판단 포인트**: 정보화사업 계획 단계 보안대책 반영, 국가정보원 보안성 검토, 운영 단계 접근권한·로그감사를 함께 써야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공공 정보시스템 보안 이해 확인 | 전자정부 정보시스템, 행정정보 보호, 정보통신망 보안조치 | 일반 웹서비스 보안으로만 서술 |
| 사업관리 연계 판단 확인 | 계획 단계 보안대책, 보안성 검토, 구축 후 운영통제 | 구축 후 취약점 점검만 언급 |
| 기술 통제 구체성 확인 | 인증, 접근통제, 로그, 암호화, 개인정보 보호 | 방화벽·백신 나열식 답안 |

> 요약: 이 문제는 전자정부 보안을 법·사업관리·기술통제·감사증적으로 연결하는 답안을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 행정 정보시스템 보호 체계
- 배경: 전자문서, 민원, 행정정보 공동이용은 국민 권리와 행정 처분 근거가 되어 위변조·유출·권한오남용 차단이 필요하다.
- 필요성: 전자정부법과 보안성 검토 기준으로 계획 단계 보안요건부터 운영 단계 로그감사까지 일관되게 통제한다.

---

## Ⅱ. 구조 및 구성요소

```text
정보화사업 계획 -> 보안대책 반영 -> 보안성 검토
  -> 인증 / 접근통제 / 암호화 -> 로그 / 감사
  -> 행정정보 공동이용 통제 -> 사고대응 / 개선권고
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 사업 계획 보안대책 | 요구사항, 예산, 일정에 보안 항목 반영 | 구축 전 통제 |
| 보안성 검토 | 설계·구성·연계 위험 사전 확인 | 국가정보원·상급기관 기준 연계 |
| 행정정보 보호 | 공동이용, 위변조 방지, 이용기록 관리 | 개인정보·민감정보 포함 |
| 운영통제 | 인증, 접근권한, 로그감사, 암호화 | 지속 점검 대상 |

> 요약: 전자정부 보안은 계획, 검토, 기술통제, 행정정보 이용기록, 사고대응이 연결된 공공 시스템 보호 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 도출 -> 정보자산 분류 -> 보안성 검토 요청
  -> 설계 보완 -> 구현 / 시험 -> 권한부여
  -> 운영 로그 수집 -> 이상행위 탐지 -> 조치 / 감사
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 정보화사업 계획에 보안 요구사항 반영 | 보안요구사항 명세서 |
| 2 | 보안성 검토로 연계·망·인증 구조 확인 | 검토의견 조치율 100% |
| 3 | 인증·접근통제·암호화 구현 | MFA, RBAC, TLS 1.3, DB 암호화 |
| 4 | 로그·감사·행정정보 이용기록 수집 | 원문조회 로그, 관리자 행위 로그 |
| 5 | 이상행위 탐지와 개선권고 이행 | 탐지 룰, 조치기한, 재점검 |

> 요약: 전자정부 보안은 계획 단계 검토의견을 구현 통제로 반영하고 운영 로그로 권한오남용을 추적하는 절차로 동작한다.

## Ⅳ. 특징

| 구분 | 일반 민간 시스템 | 전자정부 보안 요건 | 수치·기준 |
|:---|:---|:---|:---|
| 사업관리 | 출시 일정 중심 | 계획 단계 보안대책 반영 | 보안성 검토 의견 조치율 100% |
| 데이터 | 서비스 데이터 | 행정정보·전자문서 | 위변조 방지, 원문조회 기록 |
| 접근통제 | 계정 권한 | 업무권한·기관역할 기반 | RBAC, MFA, 권한 정기점검 |
| 감사 | 장애 로그 중심 | 행정정보 이용·관리자 행위 감사 | 로그 보관 1년 이상 기준 |

> 요약: 전자정부 보안은 국민 행정정보와 행정행위의 신뢰성을 보호하기 위해 계획 단계 검토와 운영 감사가 결합된다.

| 책임 구조 | 개발·운영팀 중심 | 발주기관, 검토기관, 운영기관 분리 | 공공 정보화사업 |

> 요약: 권한오남용, 정보유출, 설계 취약은 권한 검토, 조회 로그, 보안성 검토 조치율로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|

| 암호화 | TLS 1.3, AES-256 저장암호화 | 설정 점검, 키관리 대장 |
| 로그·감사 | 관리자·원문조회 로그 1년 이상 보관 | SIEM, 감사 샘플링 |

> 요약: 전자정부 보안 성숙도는 인증·권한 정합성, 암호화 설정, 로그 보관·감사 가능성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 계획 단계: 제안요청서에 보안성 검토, 개인정보 영향평가, 망연계, 암호화, 로그요건을 별도 요구사항으로 반영
2. 구축 단계: MFA, RBAC, TLS 1.3, AES-256, API 접근토큰 만료 1시간, 관리자 행위 로그를 표준 아키텍처에 포함
3. 운영 단계: 분기별 권한 재검토, 원문조회 이상탐지, 보안성 검토 의견 조치율 100%, 로그 보관 1년 이상을 점검표로 관리

**결론 (2줄):**
- 기술사 판단: 전자정부 정보시스템은 구축 속도보다 행정정보 보호와 감사 가능한 통제 증적을 우선 설계해야 함
- 향후 방향: 클라우드 전환과 기관 간 API 연계 확대에 따라 Zero Trust, API Gateway, SIEM 기반 통합 감사로 발전함
