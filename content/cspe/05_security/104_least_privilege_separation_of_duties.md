# 📖 【암기용】 개념 완전 이해

> 목적: 최소 권한·직무 분리를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 최소 권한은 필요한 권한만 주는 원칙이고, 직무 분리는 한 사람이 승인·실행·검증을 모두 하지 못하게 나누는 통제임
- **왜 필요한가**: 과다 권한은 실수와 침해 피해 범위를 키우고, 직무 미분리는 내부자 부정과 로그 조작을 가능하게 한다.
- **핵심 직관**: 금고 담당자가 돈을 꺼내고 장부 승인까지 혼자 못 하게 하는 원리임

## 깊이 이해
- **배경·문제의식**: 시스템 운영에서는 편의를 위해 admin 권한을 넓게 주는 일이 많다. 그러나 개발자, 배포자, 승인자, 감사자가 한 사람에게 모이면 오류·부정·은폐가 같은 경로에서 발생한다.
- **작동 원리**: 업무를 역할로 나누고 권한을 업무 수행에 필요한 최소 범위로 부여한다. 충돌 역할은 SoD Matrix로 금지하고, 예외는 승인·기간·사후 검토 조건을 붙인다.
- **비유**: 은행에서 대출 상담, 심사, 승인, 송금, 감사가 각각 다른 담당자에게 나뉘는 것과 같음
- **구체 예시**: 개발자는 코드 작성 권한만 보유하고, 운영 배포는 CI/CD 파이프라인과 승인자가 수행한다. 운영 DB 직접 UPDATE 권한은 장애 티켓 기준 30분 JIT로 부여한다.
- **흔한 오해·주의점**: 최소 권한은 업무를 막는 정책이 아니다. 기본 권한을 줄이고, 필요 시 승인된 임시 권한으로 처리해 책임 추적을 남기는 설계임

## 연결 개념
- RBAC·ABAC — 권한 단위와 조건을 정의하는 접근 제어 모델
- PAM — 특권 권한을 JIT 방식으로 부여·회수
- 내부통제 — 승인, 실행, 검토 역할을 분리하는 거버넌스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 최소 권한·직무 분리는 원칙 선언이 아니라 권한 설계, 충돌 통제, 예외 처리, 정기 검토로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 최소 권한은 업무에 필요한 권한만 부여하고, 직무 분리는 상충 업무를 다른 주체로 나누는 통제 원칙이다.
> 2. **가치**: 침해 시 피해 범위를 줄이고, 승인·실행·검증 분리로 내부자 부정과 오류 은폐 가능성을 낮춘다.
> 3. **판단 포인트**: Role Mining, SoD Matrix, JIT 권한, 정기 Access Review를 함께 적용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 접근통제 원칙 이해 확인 | Need-to-know, Least Privilege, SoD 차이 | "권한을 적게 준다" 수준으로만 설명 |
| 내부통제 설계 역량 확인 | 승인자·수행자·검토자 분리, 충돌 역할 금지 | 업무 연속성 예외 처리 누락 |
| 운영 적용 판단 확인 | RBAC, PAM, JIT, Access Review, SoD Matrix | 개발·운영·DB 권한 사례 부재 |

> 요약: 이 키워드는 보안 원칙을 실제 권한 설계와 감사 절차로 변환하는 역량을 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 권한 남용 차단 원칙
- 배경: 과다 권한과 충돌 직무는 내부자 부정, 계정 탈취 후 권한 상승, 변경 은폐의 주요 원인이 된다.
- 필요성: ISO/IEC 27001 접근통제와 내부회계 통제 기준에 맞춰 필요 권한만 부여하고 승인·실행·검증 역할을 분리해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Business Role -> Permission Set -> SoD Matrix -> Approval
                     |              |
                     +-> JIT Access
                                    +-> Access Review -> Remediation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 업무 역할 | 직무별 필요한 권한 묶음 정의 | 개발자, 운영자, 승인자, 감사자 |
| 권한 세트 | 시스템·데이터·행위 단위 권한 구성 | Read, Deploy, Update, Approve |
| SoD Matrix | 동시에 보유하면 안 되는 권한 조합 정의 | 개발+운영배포, 청구+승인 금지 |
| 예외 승인 | 긴급·임시 권한을 기간·사유 기준으로 허용 | TTL 30분, 2인 승인 |
| 정기 검토 | 권한 적정성 확인과 회수 | 고위험 90일, 일반 180일 |

> 요약: 최소 권한·직무 분리는 역할 정의, 충돌 권한 차단, 예외 승인, 정기 검토가 연결된 통제 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Job Analysis -> Role Mining -> Permission Mapping
-> SoD Conflict Check -> Approval/JIT Grant
-> Logging -> Periodic Review -> Revoke
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 직무 분석과 업무 행위 식별 | 업무별 권한 목록 100% 작성 |
| 2 | Role Mining으로 권한 세트 정리 | 중복 역할 20% 이상 축소 목표 |
| 3 | SoD 충돌 검사와 승인 분리 적용 | 충돌 권한 보유 0건 |
| 4 | 필요 시 JIT 권한 부여와 로그 기록 | TTL 30분, 승인 티켓 필수 |
| 5 | 정기 권한 검토 후 회수 | 미사용 권한 30일 기준 제거 |

> 요약: 권한은 업무 분석에서 시작해 충돌 검사, 임시 부여, 정기 회수로 순환 관리해야 한다.

---

## Ⅳ. 특징

| 구분 | 과다 권한 운영 | 최소 권한·직무 분리 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 권한 범위 | 팀 단위 포괄 권한 | 업무 행위별 권한 | 미사용 권한 30일 기준 회수 |
| 업무 충돌 | 승인·실행 겸임 | 승인자·수행자·검토자 분리 | SoD 충돌 0건 |
| 예외 처리 | 상시 admin 부여 | JIT 임시 권한 | TTL 30분, 사유 코드 필수 |
| 감사 | 권한 목록 사후 확인 | 변경 이력·승인·로그 연계 | 고위험 90일 검토 |

> 요약: 최소 권한은 권한 범위를 줄이고, 직무 분리는 권한 조합을 제한해 침해와 내부 부정 경로를 나눈다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 부서별 일괄 권한 | 직무 기반 권한+SoD Matrix | 동일 권한 사용자 100명 이상이면 Role Mining |
| 운영 | 수동 요청·승인 | Workflow+JIT+Access Review | 권한 변경 월 50건 이상이면 자동화 |
| 통제 | 사후 감사 중심 | 사전 충돌 차단+사후 검토 | 금융·개인정보·운영망에 필수 |

> 요약: 권한 수와 변경 빈도가 커질수록 수동 승인보다 역할 분석과 SoD 자동 검사가 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 지연 | 권한 과소 부여 | 표준 역할 템플릿, JIT 예외 절차 | 권한 승인 평균 4시간 이하 |
| 충돌 누락 | SoD Matrix 미정의 | 업무 프로세스별 금지 조합 등록 | 충돌 권한 0건 |
| 권한 누적 | 부서 이동 후 회수 누락 | Mover 프로세스, 90일 검토 | Orphan 권한 0건 |

> 요약: 최소 권한의 운영 리스크는 업무 지연, 충돌 누락, 권한 누적이며 표준 역할과 정기 검토로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 권한 적정성 | 미사용 권한 30일 기준 제거율 95% 이상 | IAM/IGA 권한 리포트 |
| SoD 통제 | 충돌 권한 보유 0건, 예외 승인 100% | SoD Engine, 감사 샘플 |
| 예외 운영 | JIT 권한 TTL 30분, 사후 검토 24시간 | PAM 로그, 티켓 시스템 |

> 요약: 권한 적정성, SoD 충돌, JIT 예외 운영을 지표로 관리해야 원칙이 실제 통제로 작동한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 직무 분석으로 표준 역할을 정의하고 Role Mining으로 중복 역할 20% 이상 축소 목표를 설정
2. 개발·배포, 청구·승인, DB수정·감사 권한을 SoD Matrix에 등록해 충돌 권한 보유를 0건으로 관리
3. 운영 예외는 PAM 기반 JIT 30분 권한으로 처리하고 고위험 권한은 90일마다 Access Review 수행

**결론 (2줄):**
- 기술사 판단: 업무 연속성이 우선인 권한은 표준 역할로, 고위험 예외는 JIT와 사후 검토로 분리함
- 향후 방향: IAM·PAM·CI/CD 권한을 통합해 사람과 서비스 계정 모두에 최소 권한을 적용함
