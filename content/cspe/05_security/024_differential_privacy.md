# 📖 【암기용】 개념 완전 이해

> 목적: 차등 프라이버시를 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 한 개인의 데이터 포함 여부가 통계 결과에 미치는 영향을 수학적으로 제한하는 프라이버시 보호 기법
- **왜 필요한가**: 익명화된 통계라도 외부 보조정보와 결합하면 재식별될 수 있다. 차등 프라이버시는 결과에 잡음을 넣어 개인 1명의 존재가 드러나는 정도를 epsilon으로 제한한다.
- **핵심 직관**: 설문 결과에 아주 작은 흔들림을 넣어도 전체 경향은 보이지만 특정 사람이 참여했는지는 구분하기 어렵게 만드는 방식이다.

## 깊이 이해
- **배경·문제의식**: k-익명성은 데이터셋 모양을 바꾸지만 공격자가 배경지식을 가지면 민감 속성을 추론할 수 있다. 통계 API와 AI 학습 로그도 반복 질의로 개인 정보를 노출할 수 있다.
- **작동 원리**: 두 데이터셋이 한 사람의 레코드만 다를 때, 같은 결과가 나올 확률 비율을 e^epsilon 이내로 제한한다. delta는 작은 실패 확률을 의미하며, Laplace·Gaussian 메커니즘은 민감도에 맞춰 잡음을 추가한다.
- **비유**: 회의실 인원수를 발표할 때 실제 숫자에 주사위 잡음을 더해 발표하면 전체 규모는 알 수 있지만 특정 한 사람이 들어왔는지는 알기 어렵다.
- **구체 예시**: epsilon 0.1은 프라이버시 보호가 크지만 통계 오차가 증가하고, epsilon 10은 분석 정확도는 높지만 개인 영향이 크게 드러난다. 반복 질의는 privacy budget을 소진한다.
- **흔한 오해·주의점**: 차등 프라이버시는 암호화가 아니다. 원본 접근통제, 목적 제한, 비식별 처리, 모델 학습 파이프라인 통제와 함께 적용해야 한다.

## 연결 개념
- k-익명성 — 데이터 배포형 비식별 처리의 기준
- 동형 암호·MPC — 원본 비공개 계산 후 결과 공개에 DP 결합
- 연합 학습 — 클라이언트 업데이트에 DP-SGD 적용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 차등 프라이버시는 개인 1명 포함 여부가 통계 결과 확률에 미치는 영향을 epsilon, delta로 제한하는 수학적 프라이버시 모델임.
> 2. **가치**: 통계 공개, 로그 분석, AI 학습에서 재식별·멤버십 추론 공격 위험을 정량 통제함.
> 3. **판단 포인트**: epsilon/delta, sensitivity, noise mechanism, privacy budget, utility loss, 규제 목적 제한을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 원리 이해 | epsilon, delta, sensitivity, Laplace/Gaussian noise | "잡음 추가"만 쓰고 privacy budget 누락 금지 |
| 재식별 위험 판단 | 멤버십 추론, 반복 질의, 보조정보 공격 | k-익명성과 동일 개념으로 설명 금지 |
| 적용 설계 | 질의 제한, 예산 회계, 정확도 손실 측정 | epsilon 값 선택 근거 없이 제시 금지 |

> 요약: 차등 프라이버시 답안은 재식별 위협을 epsilon 예산과 정확도 손실의 교환 관계로 설명해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 확률적 프라이버시 보호
- 배경: 개인정보 통계·AI 학습은 식별자를 제거해도 보조정보와 반복 질의로 개인 존재 여부가 추론될 수 있음.
- 필요성: 차등 프라이버시는 민감도 기반 잡음과 프라이버시 예산 epsilon 회계로 개인 1명의 영향도를 정량 제한함.

---

## Ⅱ. 구조 및 구성요소

```text
Raw Data -> Query/Training Function -> Sensitivity Analysis
-> Noise Mechanism -> Privacy Accountant -> DP Output
/ Governance -> Purpose Limit / Access Control / Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Query/Function | 공개할 통계·모델 학습 함수 | count, mean, DP-SGD |
| Sensitivity | 개인 1명이 결과에 주는 최대 영향 | clipping, bounding 필요 |
| Noise mechanism | 민감도와 epsilon에 따른 잡음 추가 | Laplace, Gaussian |
| Privacy accountant | 누적 epsilon/delta 관리 | 반복 질의·composition 통제 |

> 요약: DP 구조는 함수 민감도 산정, 잡음 추가, 예산 회계를 결합해 출력 단계의 개인정보 노출을 제한함.

---

## Ⅲ. 동작원리 및 흐름도

```text
위협 모델 정의 -> 함수 민감도 계산 -> epsilon/delta 설정
-> 잡음 분포 선택 -> 결과 생성 -> 예산 차감 -> 정확도 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 멤버십 추론·재식별 위협 정의 | 공격 시나리오 문서화 |
| 2 | 함수별 sensitivity 산정 | 입력 범위·clipping 기준 |
| 3 | epsilon/delta와 noise 선택 | 정책 승인, utility target |
| 4 | 결과 공개·예산 차감 | 누적 epsilon 한도 |
| 5 | 정확도·프라이버시 점검 | 오차율, 공격 성공률 |

> 요약: DP는 잡음 크기보다 민감도 산정과 누적 예산 관리가 운영 성패를 결정함.

## Ⅳ. 특징

| 구분 | k-익명성·마스킹 | 차등 프라이버시 | 판단 포인트 |
|:---|:---|:---|:---|
| 보호 대상 | 배포 데이터셋 식별자 | 출력 결과의 개인 영향 | 통계 API·모델 공개 적합 |
| 보안 근거 | 준식별자 일반화 | 확률 비율 epsilon 제한 | 보조정보 공격 내성 |
| 비용 | 정보 손실·범주화 | 잡음으로 정확도 손실 | 오차율, confidence interval |
| 운영 | 1회 배포 중심 | 반복 질의 예산 관리 | privacy budget, composition |

> 요약: 차등 프라이버시는 데이터셋 형태보다 출력 확률을 통제하므로 반복 질의와 AI 학습 환경에 적합함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 익명화 데이터 배포 | DP API·DP 학습 | 반복 질의·모델 공개 여부 |
| 비용/성능 | 정확도 보존 중심 | epsilon 작을수록 오차 증가 | 허용 오차율 1%~5% |
| 운영/위험 | 배포 전 심사 | 예산 회계·질의 통제 | 감사로그, budget owner 지정 |

> 요약: 반복 분석 API나 모델 공개 환경에서는 익명화보다 DP 예산 관리가 재식별 위험 통제에 적합함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과소 잡음 | sensitivity 산정 오류 | clipping 검증, 코드 리뷰 | 재식별 공격 성공률 |
| 예산 고갈 | 반복 질의·composition | privacy accountant, rate limit | 누적 epsilon, 차단 질의 수 |
| 분석 품질 저하 | epsilon 과소 설정 | utility test, A/B 검증 | 오차율, 모델 정확도 하락폭 |

> 요약: DP 리스크는 프라이버시와 유용성의 균형 문제이며 epsilon 예산과 정확도 지표를 동시에 관리해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 프라이버시 | epsilon/delta 정책 준수, budget 초과 0건 | accountant 로그 |
| 정확도 | 통계 오차율 1%~5%, 모델 정확도 하락폭 | holdout test, confidence interval |
| 규제 대응 | 목적 제한, 최소 공개, 감사 추적 | PIA, ISMS-P 점검 |

> 요약: DP 도입은 epsilon 예산, 오차율, 감사 가능성으로 성공 여부를 판단해야 함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 통계 공개, 로그 분석, DP-SGD 학습을 구분하고 함수별 sensitivity와 clipping 범위를 문서화.
2. epsilon/delta 정책, privacy accountant, 질의 rate limit, budget owner를 지정해 반복 질의와 composition 통제.
3. 재식별 공격 테스트, utility test, PIA를 배포 승인 조건으로 두고 개인정보보호법 목적 제한과 감사로그 연계.

**결론 (2줄):**
- 기술사 판단: 정적 데이터 배포는 k-익명성·가명처리, 반복 질의·AI 학습 공개는 차등 프라이버시를 적용함.
- 향후 방향: 마이데이터·AI 학습 데이터 활용은 DP+MPC+연합학습 결합으로 규제 대응과 분석 유용성을 함께 확보해야 함.
