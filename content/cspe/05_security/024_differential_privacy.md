# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 차등 프라이버시(DP)는 **프라이버시 강화 기술(PET)** 중 하나로, 한 개인의 데이터 포함 여부가 통계 결과에 미치는 영향을 **epsilon(ε)** 이라는 수학적 파라미터로 제한하는 확률적 프라이버시 보호 기법임.
- **왜 필요한가**: 식별자를 제거한 통계라도 외부 보조정보와 결합하면 재식별이 가능하고, 반복 질의를 통해 개인 존재 여부를 추론할 수 있음(멤버십 추론 공격). DP는 결과에 잡음을 넣어 개인 1명의 존재 여부를 수학적으로 구분할 수 없게 함.
- **핵심 직관**: 설문 결과에 아주 작은 흔들림을 넣어도 전체 경향은 보이지만, 특정 사람이 참여했는지는 구분하기 어려워지는 방식임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| PET (상위 키워드) | Privacy Enhancing Technologies — 개인정보 보호 강화 기술 총칭 | 프라이버시 방어 도구 모음 |
| ε (epsilon) | 프라이버시 손실 파라미터 — 작을수록 보호 강화, 정확도 하락 | 잡음의 양을 조절하는 다이얼 |
| δ (delta) | ε 보장이 실패할 수 있는 극소 확률 | 보호 보증이 빗나갈 확률 |
| Sensitivity | 개인 1명이 함수 결과에 주는 최대 영향량 | 한 표가 투표 결과를 바꿀 수 있는 정도 |
| Laplace mechanism | sensitivity/ε 크기의 Laplace 분포 잡음 추가 | 주사위를 굴려 결과에 더하기 |
| Gaussian mechanism | (ε, δ)-DP를 위한 정규 분포 잡음 추가 | 종형 곡선 잡음 더하기 |
| Privacy Budget | 누적 ε — 질의를 반복할수록 소진됨 | 잡음 보호막의 남은 두께 |
| Privacy Accountant | 누적 ε/δ를 추적·관리하는 시스템 | 보호막 두께 계측기 |
| Composition | 여러 질의의 ε이 합산되는 원리 | 보호막이 질의마다 얇아짐 |
| DP-SGD | 딥러닝 학습 시 그래디언트에 DP 잡음을 추가하는 기법 | 학습 과정에서 개인 흔적 지우기 |
| Clipping | sensitivity를 제한하기 위해 입력·그래디언트를 범위 내로 자르는 작업 | 튀는 값을 잘라 잡음 크기를 안정화 |

## 깊이 이해
- **배경·문제의식**: k-익명성(163)은 데이터셋의 준식별자를 일반화해 개인을 숨기지만, 공격자가 배경지식을 가지면 민감 속성을 추론할 수 있음. 통계 API·AI 학습 로그도 반복 질의로 개인 정보를 노출할 수 있음. 동형 암호(021)·MPC(023)가 "원본을 보지 않고 계산"이라면, DP는 "결과를 봐도 개인 존재를 알 수 없게"하는 접근으로 목적이 다름 — 두 기법은 결합해 쓰는 경우가 많음.
- **작동 원리**: (1) 두 데이터셋 D와 D'가 한 사람의 레코드만 다를 때, 같은 결과가 나올 확률 비율을 e^ε 이내로 제한함 — 이것이 ε-DP의 수학적 정의임. (2) ε이 작으면 두 데이터셋의 결과가 거의 구분 불가능(강한 보호, 큰 잡음), ε이 크면 개인 영향이 드러남(약한 보호, 작은 잡음). (3) sensitivity를 산정한 뒤, Laplace(순수 DP) 또는 Gaussian((ε,δ)-DP) 메커니즘으로 잡음을 추가함. (4) 반복 질의는 composition 정리에 의해 ε이 누적되므로, privacy accountant로 예산을 추적·차단함.
- **비유**: 회의실 인원수를 발표할 때 실제 숫자에 주사위 잡음을 더해 발표하면 전체 규모는 알 수 있지만, 특정 한 사람이 들어왔는지는 알기 어려움. 발표를 반복할수록 잡음 효과가 줄어들므로(composition) 발표 횟수를 제한해야 함.
- **구체 예시**: ε=0.1은 강한 보호이나 통계 오차가 증가하고, ε=10은 분석 정확도는 높지만 개인 영향이 크게 드러남. Apple은 사용 패턴 수집에 ε=2~8, Google은 RAPPOR에 ε=2.5를 적용한 사례가 있음. DP-SGD로 학습한 모델은 멤버십 추론 공격 성공률이 50%(random guess) 수준으로 떨어짐.
- **흔한 오해·주의점**: (1) DP는 암호화가 아님 — 원본 접근통제·목적 제한·비식별 처리·모델 학습 파이프라인 통제와 함께 적용해야 함. (2) ε 값이 작다고 무조건 좋은 것이 아님 — 분석 유용성(utility)과의 균형이 핵심임. (3) sensitivity 산정을 잘못하면 잡음이 부족해 보호가 깨짐 — clipping 범위 검증이 필수임.

## 연결 개념
- **k-익명성·l-다양성(163)**: 데이터 배포형 비식별 처리의 기준 — DP는 출력 확률을 통제하는 차이가 있음
- **동형 암호(021)·MPC(023)**: 원본 비공개 계산 후 결과 공개 시 DP를 결합해 재식별을 방지
- **연합 학습(168)**: 클라이언트 그래디언트 업데이트에 DP-SGD를 적용해 개인 데이터 추론을 방지

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DP는 개인 1명 포함 여부가 통계 결과 확률에 미치는 영향을 ε/δ로 제한하는 수학적 프라이버시 모델임.
> 2. **가치**: 통계 공개·로그 분석·AI 학습에서 재식별·멤버십 추론 공격 위험을 정량 통제함.
> 3. **판단 포인트**: ε/δ 설정·sensitivity 산정·noise mechanism·privacy budget·utility loss·규제 목적 제한을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DP 원리 이해 | ε/δ 정의·sensitivity·Laplace/Gaussian noise | "잡음 추가" 한 줄로 끝내고 privacy budget 누락 |
| 재식별 위험 판단 | 멤버십 추론·반복 질의·보조정보 공격 | k-익명성과 동일 개념으로 설명 |
| 적용 설계 | 질의 제한·예산 회계·정확도 손실 측정 | ε 값 선택 근거 없이 제시 |

> 요약: DP 답안은 재식별 위협을 ε 예산과 정확도 손실(utility)의 교환 관계로 설명해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 개인 1명의 데이터 포함 여부가 통계 결과에 미치는 영향을 ε으로 제한하는 확률적 프라이버시 모델임.
- 배경: 식별자를 제거한 통계라도 보조정보·반복 질의로 개인 존재 여부가 추론될 수 있음(k-익명성의 한계).
- 필요성: sensitivity 기반 잡음과 ε 예산 회계로 개인 1명의 영향도를 정량 제한하여 통계 공개·AI 학습의 프라이버시를 보장함.

---

## Ⅱ. 구조 및 구성요소

```text
Raw Data -> Query/Training Function -> Sensitivity Analysis
  -> Noise Mechanism(Laplace/Gaussian) -> Privacy Accountant
  -> DP Output
  / Governance -> Purpose Limit / Access Control / Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Query/Function | 공개할 통계·모델 학습 함수 | count, mean, histogram, DP-SGD |
| Sensitivity | 개인 1명이 결과에 주는 최대 영향량 | clipping·bounding으로 범위 제한 |
| Noise Mechanism | sensitivity와 ε에 따른 잡음 분포 추가 | Laplace(순수 DP), Gaussian((ε,δ)-DP) |
| Privacy Accountant | 누적 ε/δ 추적·예산 초과 시 질의 차단 | composition 정리 기반 |

> 요약: DP 구조는 함수 sensitivity 산정→잡음 추가→예산 회계를 결합해 출력 단계의 개인정보 노출을 제한함.

---

## Ⅲ. 동작원리 및 흐름도

```text
위협 모델 정의 -> 함수별 Sensitivity 산정 -> ε/δ 설정
  -> 잡음 분포 선택(Laplace/Gaussian) -> 결과 생성
  -> Privacy Accountant 예산 차감 -> 정확도 검증
```

1. 위협 정의: 멤버십 추론·재식별·반복 질의 시나리오를 문서화하고, 보호 대상과 공격 모델을 확정함.
2. Sensitivity·ε 설정: 함수별 sensitivity를 산정하고(clipping 범위 검증), 정책에 따라 ε/δ와 noise 메커니즘을 선택함.
3. 잡음 추가·예산 차감: noise를 추가해 결과를 생성하고, privacy accountant가 누적 ε을 차감함 — 예산 한도 도달 시 추가 질의를 차단함.
4. 정확도 검증: 오차율·모델 정확도 하락폭을 holdout test·confidence interval로 측정해 utility가 허용 범위 내인지 확인함.

> 요약: DP는 잡음 크기보다 sensitivity 산정과 누적 예산 관리가 운영 성패를 결정함.

---

## Ⅳ. 특징

- 수학적 보증: ε-DP 정의로 개인 1명 포함 여부가 결과 확률에 미치는 영향을 e^ε 이내로 수학적 보증함.
- 사후 공격 내성: 보조정보·배경지식에 무관하게 보호가 유지됨 — k-익명성과 달리 공격자 지식 가정이 불필요함.
- 프라이버시-유용성 교환: ε이 작을수록 보호는 강하지만 잡음 증가로 통계 오차가 커짐 — 조직별 ε 정책이 핵심 의사결정임.
- Composition 누적: 반복 질의·다중 분석 시 ε이 합산되므로 privacy accountant에 의한 예산 관리가 필수임.
- AI 학습 적용: DP-SGD로 그래디언트에 잡음을 추가해 학습 모델에서 멤버십 추론 공격 성공률을 ~50%(random guess)로 낮춤.

## Ⅴ. 심화 비교 및 적용 판단

DP(출력 확률 통제)와 k-익명성(데이터 변형)을 보호 방식·적용 환경·운영 축으로 비교함.

| 구분 | k-익명성/마스킹 | 차등 프라이버시(DP) | 선택 기준 |
|:---|:---|:---|:---|
| 보호 대상 | 배포 데이터셋의 식별자·준식별자 | 출력 결과의 개인 영향도(확률) | 통계 API·모델 공개 여부 |
| 보안 근거 | 준식별자 일반화(k명 이상 동일 그룹) | 확률 비율 ε 제한(수학적 보증) | 보조정보 공격 내성 |
| 비용 | 정보 손실·범주화 | 잡음으로 정확도 손실(오차율 1~5%) | utility 허용 범위 |
| 운영 | 1회 배포 중심 | 반복 질의 예산 관리(composition) | privacy budget·rate limit |

> 요약: 정적 데이터 배포는 k-익명성·가명처리를, 반복 질의·모델 공개 환경은 DP 예산 관리를 적용함.

**리스크·대응:**
- 과소 잡음: sensitivity 산정 오류로 보호 부족 → clipping 검증·코드 리뷰 (지표: 재식별 공격 성공률)
- 예산 고갈: 반복 질의·composition으로 ε 한도 초과 → privacy accountant·rate limit (지표: 누적 ε, 차단 질의 수)
- 분석 품질 저하: ε 과소 설정으로 utility 부족 → utility test·A/B 검증 (지표: 오차율, 모델 정확도 하락폭)

**도입 후 점검 지표:**
- 프라이버시: ε/δ 정책 준수·budget 초과 0건 — accountant 로그
- 정확도: 통계 오차율 1~5%·모델 정확도 하락폭 — holdout test·confidence interval
- 규제 대응: 목적 제한·최소 공개·감사 추적 — PIA·ISMS-P 점검

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 통계 공개·로그 분석·DP-SGD 학습을 구분하고 함수별 sensitivity와 clipping 범위를 문서화함.
2. ε/δ 정책·privacy accountant·질의 rate limit·budget owner를 지정해 반복 질의와 composition을 통제함.
3. 재식별 공격 테스트·utility test·PIA를 배포 승인 조건으로 두고, 개인정보보호법 목적 제한과 감사로그를 연계함.

**결론:**
- 기술사 판단: 정적 데이터 배포는 k-익명성·가명처리를, 반복 질의·AI 학습 공개는 차등 프라이버시를 적용함.
- 향후 방향: 마이데이터·AI 학습 데이터 활용은 DP+MPC+연합학습 결합으로 규제 대응과 분석 유용성을 함께 확보해야 함.
