# 📖 【암기용】 개념 완전 이해

> 목적: 대칭 암호화를 처음 보는 사람도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 하나의 비밀키로 평문을 암호문으로 바꾸고 다시 평문으로 복원하는 암호 방식
- **왜 필요한가**: 대량 데이터 암호화에는 공개키 연산보다 처리량이 높은 블록 암호가 필요하다. 디스크 암호화, VPN, TLS 세션 데이터는 대부분 AES 계열로 보호된다.
- **핵심 직관**: 같은 열쇠를 가진 사람만 금고를 잠그고 열 수 있으므로, 암호 자체보다 열쇠 전달과 보관이 더 큰 문제임

## 깊이 이해
- **배경·문제의식**: DES는 56-bit 키로 전수조사 위험이 커졌고, 3DES는 112-bit 수준 보안성을 얻었지만 64-bit 블록과 처리 비용 한계가 남았다. AES는 128-bit 블록과 128/192/256-bit 키를 제공해 현대 표준 암호로 채택됨.
- **작동 원리**: 평문 블록을 키 확장 결과와 여러 라운드에서 치환(Substitution)·순열(Permutation)·혼합(MixColumns)해 암호문으로 변환한다. 복호화는 같은 비밀키와 역변환으로 수행함.
- **비유**: 같은 자물쇠 열쇠를 복사해 양쪽이 갖고 있는 구조다. 자물쇠는 튼튼해도 열쇠를 택배로 보내다 노출되면 금고 전체가 열림.
- **구체 예시**: AES-256-GCM은 256-bit 키와 96-bit nonce를 사용하고, 암호화와 인증 태그를 함께 제공해 TLS 1.3·스토리지 암호화에 사용됨.
- **흔한 오해·주의점**: "AES-256이면 끝"이 아니다. ECB 모드는 동일 평문이 동일 암호문으로 드러나므로 CBC·CTR·GCM 같은 운용 모드와 nonce 재사용 금지 조건이 필수임.

## 연결 개념
- 키 관리(KMS) — 대칭키 생성·보관·회전의 운영 통제
- 하이브리드 암호 — 공개키로 세션키를 교환하고 대칭키로 본문 암호화
- HMAC·AEAD — 기밀성 외 무결성·인증성 보완

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 수치·표준명·기술명 중심으로 작성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 대칭 암호화는 송신자와 수신자가 동일한 비밀키로 기밀성을 제공하는 암호 방식이다.
> 2. **가치**: AES-GCM·ChaCha20-Poly1305는 TLS·VPN·DB·디스크 암호화에서 대량 데이터 보호의 기본 수단임.
> 3. **판단 포인트**: 알고리즘 강도보다 키 분배, nonce 재사용, 운용 모드, 키 회전 주기가 실제 보안 수준을 좌우함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 노출 위협을 암호 통제·키 관리·탐지·복구 절차와 연결하는 보안 설계 역량 확인 | AES-GCM·ChaCha20-Poly1305, KMS/HSM, 96-bit nonce 유일성, 키 회전·폐기, 로그 기반 이상 접근 탐지 | AES 키 길이만 나열, ECB·고정 IV 누락, 기밀성·무결성·인증·부인방지 역할 혼동 |

> 요약: 대칭 암호 답안은 기밀성 제공 범위와 키·nonce 운영 통제를 함께 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

대칭 암호는 같은 키로 암복호화하는 암호이다. DES 56-bit는 전수조사 위험으로 제외되고, AES-128/256이 NIST FIPS 197 기반 표준으로 사용된다. 클라우드·DB·스토리지 암호화는 GB 단위 데이터를 처리하므로 공개키보다 대칭키 기반 세션 암호가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
Plaintext -> Mode of Operation -> AES Core -> Ciphertext
              +-> IV/Nonce
              +-> Secret Key -> Key Schedule
Ciphertext -> Tag Verify -> Decryption -> Plaintext
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 비밀키 | 암복호화 공통 입력 | AES-128/192/256-bit, KMS·HSM 보관 |
| 블록 암호 | 평문 블록 변환 | AES 128-bit 블록, DES 64-bit 블록 |
| 운용 모드 | 블록을 스트림·메시지 단위로 연결 | CBC·CTR·GCM, ECB 금지 |
| IV/Nonce | 동일 평문 반복 노출 방지 | GCM 96-bit nonce 재사용 금지 |

> 요약: 대칭 암호는 비밀키, 블록 암호, 운용 모드, IV/Nonce가 결합되어 기밀성과 반복 패턴 은닉을 제공한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성 -> 키 보관/배포 -> IV/Nonce 생성 -> 암호화
-> 암호문/태그 저장 또는 전송 -> 복호화 전 태그 검증 -> 평문 복원
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | CSPRNG로 128-bit 이상 비밀키 생성 | NIST SP 800-90A 수준 난수원 |
| 2 | AES-GCM 등 운용 모드 선택 | ECB 미사용, nonce 유일성 |
| 3 | 평문 암호화 및 인증 태그 생성 | GCM 128-bit tag 검증 |
| 4 | 키 회전·폐기 수행 | 90일·1년 등 정책 기반 회전 |

> 요약: 대칭 암호의 흐름은 키 생성부터 태그 검증과 키 폐기까지 이어지며, nonce 유일성과 키 수명 관리가 필수 통제점이다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 대량 데이터 암호화에 적합 | AES-NI 사용 시 CPU 오버헤드 한 자릿수 % 목표 |
| 한계 | 키 공유 대상이 늘수록 유출면 증가 | 사용자 N명 간 개별키는 N(N-1)/2개 필요 |
| 비교 대상 | DES·3DES·AES | DES 56-bit 금지, 3DES 신규 사용 중단, AES-256 우선 |

> 요약: 대칭 암호는 데이터 본문 암호화에 적합하나, 키 분배와 운용 모드 오류가 주요 실패 원인이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 비대칭 암호 본문 암호화 | 대칭키 세션 암호 | MB/GB 단위 본문은 AES·ChaCha20 선택 |
| 비용/성능 | RSA 연산 | AES-NI·ARMv8 Crypto Extension | TLS 본문, DB TDE, 파일 암호화 |
| 운영/위험 | 수동 키 파일 | KMS·HSM·Envelope Encryption | 키 접근 감사로그 100% 필요 |

> 요약: 본문 데이터는 대칭 암호, 키 교환은 비대칭 암호로 분리할 때 처리량과 키 관리 요구를 동시에 만족한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 키 유출 | 파일·환경변수 평문 저장 | HSM/KMS, RBAC, 키 암호화 키 분리 | KMS 접근 로그, 비인가 0건 |
| nonce 재사용 | GCM 카운터 충돌 | 96-bit nonce 유일성 검증 | nonce 중복 탐지 0건 |
| 모드 오류 | ECB·고정 IV 사용 | AES-GCM·CBC 랜덤 IV 표준화 | 정적 분석 정책 위반 0건 |

> 요약: 대칭 암호 리스크는 알고리즘보다 키 저장, nonce, 운용 모드에서 발생하므로 정책과 자동 점검으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 알고리즘 | AES-128 이상, DES/3DES 제외 | 암호 스위트 스캔 |
| 키 관리 | 키 회전 90~365일, 접근 감사 100% | KMS 정책·CloudTrail |
| 암호 운용 | ECB 0건, GCM nonce 중복 0건 | SAST·구성 스캔 |

> 요약: 도입 후 성공 여부는 허용 알고리즘, 키 회전, 금지 모드 사용 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 데이터 저장: DB TDE·파일 암호화에 AES-256-GCM 적용, 키는 KMS CMK로 Envelope Encryption 구성
2. 통신 구간: TLS 1.3에서 AES-128-GCM 또는 ChaCha20-Poly1305 사용, CBC·RC4·3DES cipher suite 차단
3. 운영 통제: 키 소유자 분리, 90~365일 회전, KMS 접근 로그 1년 이상 보관, nonce 중복 탐지 자동화

**결론 (2줄):**
- 기술사 판단: 대량 본문 보호는 AES-GCM, 키 교환은 RSA/ECC·DH와 결합하는 하이브리드 구조가 적합함
- 향후 방향: PQC 전환기에도 세션 데이터는 AES-256 유지, 키 교환부는 ML-KEM 하이브리드로 교체 필요
