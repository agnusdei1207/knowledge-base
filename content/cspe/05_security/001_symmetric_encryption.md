## 미리 알고가기

- 대칭키: 암호화와 복호화에 같은 비밀키를 쓰는 키임
- 블록 암호: 평문을 고정 크기 블록으로 나누어 암호화함
- 스트림 암호: 키스트림과 평문을 비트 또는 바이트 단위로 결합함
- 운영 모드: 블록 암호를 긴 데이터에 적용하는 방식임
- AEAD: 암호화와 무결성 검증 태그를 함께 제공하는 방식임

## Ⅰ. 개요

- **정의/개념**: 대칭 암호화는 송신자와 수신자가 같은 비밀키로 평문과 암호문을 변환하는 방식임
- **배경/필요성**: 대용량 데이터 보호에서는 공개키 암호만으로 처리 지연과 연산 비용이 커짐. 세션키 기반 데이터 암호화가 필요함

## Ⅱ. 특징

- 동일 키를 공유하므로 키 유출 시 암호화·복호화 권한이 함께 노출됨
- 블록 암호는 운영 모드와 IV·Nonce 관리가 안전성을 좌우함
- 스트림 암호는 키스트림 재사용 시 평문 관계가 드러날 수 있음
- 기밀성 제공이 주 기능이며 출처 인증과 부인방지는 별도 기술이 필요함

## Ⅲ. 종류 및 비교

| 구분 | 블록 암호 | 스트림 암호 |
|:---|:---|:---|
| 처리 단위 | 고정 길이 블록 | 비트 또는 바이트 흐름 |
| 대표 알고리즘 | AES, ARIA, SEED | ChaCha20 |
| 설계 변수 | 운영 모드, 패딩, IV | Nonce, 카운터, 키스트림 |
| 오류 영향 | 모드에 따라 인접 블록까지 확산 | 해당 위치 중심으로 영향 |
| 적용 판단 | 저장 데이터, 범용 암호화 | 실시간 통신, 소프트웨어 구현 |

> 요약: 블록 암호는 모드 선택이 안전성을 좌우하고, 스트림 암호는 키스트림 재사용 방지가 판단 기준임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 평문 | 보호 대상 원본 데이터 |
| 비밀키 | 암호화와 복호화에 공통 사용되는 값 |
| 암호 알고리즘 | 평문을 암호문으로 변환하는 연산 규칙 |
| IV·Nonce | 동일 키 사용 시 암호문 반복을 줄이는 입력값 |
| 인증 태그 | AEAD 모드에서 변조 여부를 확인하는 값 |

```text
------+   key, IV/nonce   +-----------+   ciphertext
|평문  |------------------>| 암호화    |-------------+
+------+                   +-----------+             |
                                                     v
                                               +-----------+
                                               | 복호화    |
                                               +-----------+
                                                     |
                                                     v
                                                   평문
```

## Ⅴ. 원리 및 절차 흐름도

```text
키 생성 -> 키 분배 -> IV/Nonce 생성 -> 암호화 -> 전송/저장 -> 복호화 -> 태그 검증
```

1. **키 생성**: 난수 기반으로 충분한 길이의 세션키를 생성함
2. **키 분배**: DH, KEM, KMS 등으로 동일 키를 양측에 전달함
3. **암호화**: 알고리즘과 운영 모드로 평문을 암호문으로 변환함
4. **검증**: AEAD 또는 MAC으로 변조 여부를 확인함
5. **폐기**: 세션 종료나 정책 만료 시 키를 폐기함

## Ⅵ. 실무 적용 및 유의점

- TLS는 공개키 방식으로 세션키를 합의하고 대칭 암호로 실제 데이터를 보호함
- 디스크 암호화는 키 관리와 복구 절차를 함께 설계해야 함
- CBC 모드는 패딩 오라클 위험이 있어 인증 태그 없는 사용을 피함
- GCM·ChaCha20-Poly1305는 Nonce 중복 시 안전성이 급격히 약화됨
- 키 길이는 데이터 보존 기간과 위협 모델에 맞춰 정함

## Ⅶ. 결론

- 대칭 암호화는 대용량 데이터 기밀성 보호의 실행 수단임
- 선택 기준은 단순 속도가 아니라 키 분배, 모드, Nonce, 무결성 검증 절차임

## 작성 근거(검토용)

- 대칭 암호의 판단 축을 동일 키 사용과 키 관리 위험으로 잡아 비대칭 암호와 구분함
- 기존 평가어를 제거하고 처리 단위와 운용 조건으로 설명함
- 블록·스트림 비교는 알고리즘 이름보다 운영 모드와 Nonce 관리가 답안 판단을 만든다고 보아 배치함
