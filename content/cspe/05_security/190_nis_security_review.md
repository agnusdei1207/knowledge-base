## 미리 알고가기

- 보안성 검토는 국가·공공기관 정보화사업의 보안 대책을 사업 계획 단계에서 검토하는 절차임
- 정보화사업은 정보시스템 구축, 운영, 연계, 클라우드 도입, 망 구성 변경 등을 포함함
- 보안대책서는 사업 구조, 정보 흐름, 보안 통제, 위험 대응 방안을 정리한 검토 자료임

## Ⅰ. 개요

- **정의/개념**: 국가정보원 보안성 검토는 국가·공공기관이 정보화사업을 추진할 때 사업 계획 단계에서 보안 대책의 적정성을 검토받고 보완사항을 반영하는 공공 보안 사전 통제 절차임
- **배경/필요성**: 공공 정보시스템은 행정 정보와 국가 중요 정보를 처리하므로 구축 뒤 보완하면 비용과 위험이 커짐. 사업 공고 전 설계 단계에서 보안 요구를 확정해야 함

## Ⅱ. 특징

- 사업 착수 뒤 사후 점검보다 사전 설계 검토에 초점을 둠
- 정보 흐름, 망 구성, 인증, 암호화, 외부 연계, 클라우드 이용을 함께 봄
- 검토 결과는 제안요청서, 설계서, 보안 요구사항에 반영되어야 함
- 사업 규모와 중요도에 따라 자체 검토, 상급기관 검토, 국가정보원 검토로 나뉠 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 보안성 검토 | 보안적합성 검증 |
|:---|:---|:---|
| 시점 | 사업 계획과 공고 전 | 제품 도입과 설치 이후 |
| 대상 | 정보화사업 설계와 보안 대책 | 정보보호 제품과 보안 기능 설정 |
| 목적 | 사업 구조의 보안 요구를 사전에 반영함 | 도입 제품과 설정의 적정성을 확인함 |
| 산출물 | 보안대책서, 검토 의견, 보완 요구 | 검증 결과, 보안 설정 확인, 보완 조치 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사업 계획 | 시스템 목적, 범위, 예산, 추진 일정, 외부 연계 범위를 정리한 기본 자료임 |
| 정보 흐름도 | 개인정보, 행정 정보, 중요 자료가 어디서 처리되고 이동하는지 보여 주는 구조도임 |
| 망 구성도 | 인터넷망, 업무망, 내부망, 외부 연계 구간의 분리와 접점을 검토하는 자료임 |
| 보안 요구사항 | 인증, 접근 통제, 암호화, 로그, 취약점 점검, 백업 같은 필수 통제 항목임 |
| 보완 조치 | 검토 의견을 RFP, 설계, 구축 기준에 반영하는 후속 실행 항목임 |

```text
사업 계획 -> 보안대책 수립 -> 검토 의뢰 -> 보완 요구 -> 설계/RFP 반영
```

## Ⅴ. 원리 및 절차 흐름도

```text
대상 판단 -> 자료 작성 -> 검토 요청 -> 의견 수신 -> 보완 반영 -> 사업 추진
```

1. **대상 판단**: 정보화사업의 규모, 중요도, 외부 연계, 신기술 도입 여부를 확인함
2. **자료 작성**: 보안대책서, 망 구성도, 정보 흐름도, 체크리스트를 준비함
3. **검토 요청**: 기관 내부 절차와 상급기관 경로를 통해 보안성 검토를 의뢰함
4. **의견 수신**: 검토 기관의 보완 요구와 조건을 확인함
5. **보완 반영**: RFP와 설계서와 구축 기준에 보안 요구를 반영하고 추적함

## Ⅵ. 실무 적용 및 유의점

1. 공공 클라우드와 외부 연계 사업은 공고 전 보안성 검토 의견을 RFP에 반영하고 미반영 보완 요구 수와 설계 변경 지연 일수로 사업 리스크를 관리함
2. 망 구성 변경 사업은 업무망과 인터넷망의 접점을 명확히 표시하고 망연계 승인 경로와 로그 보관 기준을 검토 항목에 넣어야 함

## Ⅶ. 결론

- 국가정보원 보안성 검토는 공공 정보화사업의 보안 요구를 구축 뒤에 고치는 절차가 아니라 사업 설계 단계에서 확정하는 사전 통제임
