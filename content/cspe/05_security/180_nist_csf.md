# 📖 【암기용】 개념 완전 이해

> 목적: NIST CSF를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 조직의 사이버 보안 위험을 공통 언어로 관리하기 위한 NIST 프레임워크
- **왜 필요한가**: 보안 통제 목록만으로는 경영진, 현업, 보안팀이 같은 위험 수준을 공유하기 어렵다. CSF는 기능, 프로파일, 티어로 현재와 목표 상태를 비교하게 함.
- **핵심 직관**: NIST CSF는 "보안 체크리스트"가 아니라 조직의 현재 보안 자세와 목표 보안 자세 사이의 갭을 관리하는 위험관리 지도임.

## 깊이 이해
- **배경·문제의식**: 산업·정부·중소조직까지 사이버 위험을 설명하는 공통 구조가 필요해 NIST CSF가 확산됨. 2024년 CSF 2.0은 Govern 기능을 추가해 보안 위험을 전사 위험관리와 연결함.
- **작동 원리**: Core의 기능·범주·하위범주로 보안 결과를 정리하고, Current Profile과 Target Profile을 만든 뒤, Implementation Tier로 위험관리 성숙도를 표현함.
- **비유**: 건강검진에서 현재 혈압·혈당을 보고 목표 수치를 정한 뒤 운동·식단 계획을 세우는 것처럼, CSF는 현재 보안 상태와 목표 상태의 차이를 줄이는 방식임.
- **구체 예시**: 랜섬웨어 대응에서 Govern은 정책·책임, Identify는 자산·취약점, Protect는 백업·접근통제, Detect는 EDR·SIEM, Respond는 IR, Recover는 DRP로 매핑함.
- **흔한 오해·주의점**: CSF는 인증 표준이 아님. ISO 27001처럼 인증서 획득을 목표로 하기보다 위험 기반 목표 프로파일과 개선 로드맵 수립에 쓰임.

## 연결 개념
- NIST CSF 2.0 - Govern, Identify, Protect, Detect, Respond, Recover 6개 기능 구조임
- ISO/IEC 27001 - 인증 가능한 ISMS 표준이며 CSF 결과와 통제 매핑 가능함
- NIST RMF - 시스템 보안 인가 중심, CSF는 조직 위험관리 공통 언어 중심임

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: NIST CSF 답안은 기능명 암기가 아니라 Govern 추가 의미, Profile·Tier 기반 갭 관리, 지표화 방안을 써야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NIST CSF는 사이버 보안 위험을 Govern·Identify·Protect·Detect·Respond·Recover 기능으로 관리하는 유연한 프레임워크임.
> 2. **가치**: Current/Target Profile과 Tier를 통해 경영진이 보안 투자 우선순위와 잔여위험을 비교할 수 있음.
> 3. **판단 포인트**: CSF 2.0의 Govern 기능은 정책·책임·공급망·위험전략을 다른 5개 기능의 기준으로 둠.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CSF 구조 이해 확인 | 6개 기능, Category, Subcategory, Profile, Tier | 1.1의 5개 기능만 작성 |
| CSF 2.0 변화 확인 | Govern 추가, 공급망 위험, 전사 위험관리 연계 | Govern을 단순 관리 항목으로 축소 |
| 실무 적용 판단 확인 | 현재/목표 프로파일 갭, 로드맵, KPI | 인증 표준처럼 설명 |

> 요약: NIST CSF 문제는 6개 기능과 Profile·Tier로 보안 개선 로드맵을 만드는 능력을 확인함.

---

## Ⅰ. 개요 및 필요성

NIST CSF는 사이버 보안 위험관리 프레임워크임. 조직은 보안 통제, 공급망, 사고대응, 복구를 경영 언어로 설명해야 하므로 공통 구조가 필요함. CSF 2.0은 Govern을 중심에 두어 보안 전략과 전사 위험관리를 연결함.

---

## Ⅱ. 구조 및 구성요소

```text
Govern -> Identify -> Protect -> Detect -> Respond -> Recover
  -> Current Profile / Target Profile
  -> Tier 평가 -> Gap 분석 -> 개선 로드맵
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Core | 기능·범주·하위범주로 보안 결과 정리 | 6개 Function, 결과 중심 |
| Profile | 현재 상태와 목표 상태 정의 | Current, Target, Community Profile |
| Tier | 위험관리 관행의 성숙도 표현 | Partial부터 Adaptive까지 |
| Informative References | 다른 표준·통제와 매핑 | ISO 27001, SP 800-53 등 |

> 요약: CSF는 Core로 구조화하고 Profile로 목표를 잡으며 Tier로 성숙도와 우선순위를 판단함.

---

## Ⅲ. 동작원리 및 흐름도

```text
조직 범위·위험전략 정의 -> Current Profile 작성
  -> Target Profile 설정 -> Gap 분석
  -> 우선순위·예산·로드맵 수립 -> 지표 모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 조직 범위, 자산, 규제, 공급망 요구 식별 | Govern·Identify 산출물 |
| 2 | Current Profile과 Tier 평가 | 통제 이행률, 사고 지표 |
| 3 | Target Profile과 갭 분석 | 위험 허용도, 목표 성숙도 |
| 4 | 개선 로드맵 실행·측정 | KPI, KRI, 잔여위험 보고 |

> 요약: CSF 적용은 현재 프로파일과 목표 프로파일의 갭을 위험 기반 로드맵으로 줄이는 방식임.

---

## Ⅳ. 특징

| 구분 | 기존/대안 | 본 기술 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 구조 | CSF 1.1 5개 기능 | CSF 2.0 6개 기능 | Govern 추가 |
| 목적 | 통제 체크리스트 | 보안 결과·위험관리 | Profile 갭 감소율 |
| 적용 | 특정 산업 중심 | 모든 규모 조직 적용 | 조직별 위험 허용도 반영 |
| 인증 | 인증서 취득 | 자가 평가·로드맵 | Tier, KPI, KRI 보고 |

> 요약: NIST CSF는 인증 요구사항보다 조직별 보안 목표와 갭 개선을 위한 위험관리 프레임워크임.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| ISO 27001 | 인증 가능한 ISMS | 유연한 위험관리 프레임워크 | 대외 인증이면 ISO, 로드맵이면 CSF |
| NIST SP 800-53 | 상세 통제 카탈로그 | 결과 중심 상위 구조 | 통제 구현 세부화 시 800-53 매핑 |
| CIS Controls | 기술 통제 우선순위 | 경영·복구 포함 전사 구조 | 중소조직 기술 착수는 CIS 병행 |
| NIST RMF | 시스템 인가 절차 | 조직 보안 자세 관리 | 시스템 인가와 전사 지표 구분 |

> 요약: CSF는 단독 통제집보다 여러 표준을 경영 위험관리 언어로 묶는 상위 프레임워크로 쓰임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 기능명 암기 | Profile·Tier 미사용 | 현재/목표 프로파일 작성 의무화 | Profile 갭 항목 수 |
| Govern 누락 | CSF 1.1 기준 답안 | 정책·책임·공급망·위험전략 포함 | Govern Category 커버리지 |
| 로드맵 미실행 | 과제 소유자·예산 부재 | 우선순위, 담당자, 분기 KPI 지정 | 개선 과제 완료율 90% 이상 |

> 요약: CSF 적용 실패는 기능명 부족보다 Profile 갭과 Govern 책임을 실행 로드맵으로 못 바꾸는 데서 발생함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| Profile 갭 | 고위험 갭 분기별 20% 이상 감소 | CSF 평가표, GRC 대시보드 |
| Detect·Respond | MTTD 30분, MTTR 4시간 등 목표 | SIEM·SOAR 지표 |
| Recover | 핵심 서비스 RTO/RPO 달성률 95% 이상 | DR Drill, BCP 훈련 |

> 요약: CSF 운영 성과는 기능별 통제 수가 아니라 Profile 갭, 탐지·대응시간, 복구 목표 달성률로 판단함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. CSF 2.0 6개 기능으로 Current Profile을 작성하고 공급망, 클라우드, 랜섬웨어 항목을 Govern에 포함함.
2. Target Profile을 위험 허용도와 규제 요구사항에 맞춰 설정하고 갭별 담당자, 예산, 분기 완료 목표를 배정함.
3. MTTD 30분, MTTR 4시간, 고위험 갭 20% 감소, RTO/RPO 달성률 95%를 KPI·KRI로 보고함.

**결론 (2줄):**
- 기술사 판단: 대외 인증 목적은 ISO 27001, 전사 보안 개선 로드맵과 경영 보고 목적은 NIST CSF를 우선 적용함.
- 향후 방향: CSF 2.0 Govern 기능을 공급망 보안, AI 보안, 클라우드 위험관리 지표와 통합함.
