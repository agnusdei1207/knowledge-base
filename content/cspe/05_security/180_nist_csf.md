## 미리 알고가기

- NIST CSF는 조직의 사이버보안 활동을 공통 기능과 결과 중심으로 정리한 프레임워크임
- CSF Core는 기능, 범주, 하위범주로 보안 활동 결과를 구조화한 핵심 체계임
- Profile은 현재 수준과 목표 수준을 비교해 개선 우선순위를 잡는 적용 산출물임

## Ⅰ. 개요

- **정의/개념**: NIST CSF는 조직이 사이버보안 위험을 이해, 평가, 우선순위화, 소통하도록 돕는 결과 중심 사이버보안 위험 관리 프레임워크임
- **배경/필요성**: 조직마다 보안 성숙도와 규제 환경이 달라 단일 통제 목록만으로는 관리가 어려움. 공통 언어로 현재 상태와 목표 상태를 비교할 기준이 필요함

## Ⅱ. 특징

- 특정 제품이나 절차를 강제하지 않고 고수준 보안 결과를 제시함
- 규모와 산업이 다른 조직도 공통 기능 기준으로 위험을 설명할 수 있음
- Current Profile과 Target Profile 비교로 투자 우선순위를 정하기 좋음
- 다른 표준과 매핑해 기존 ISMS, ISO 27001, 내부 통제와 함께 쓸 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 통제 목록 중심 접근 | NIST CSF |
|:---|:---|:---|
| 표현 방식 | 해야 할 통제를 나열함 | 달성해야 할 보안 결과를 구조화함 |
| 적용 유연성 | 조직 상황 반영이 약할 수 있음 | 규모와 위험 수준에 맞게 프로파일링함 |
| 소통 대상 | 보안 담당자 중심 | 경영진, 현업, 감사와 함께 소통 가능 |
| 개선 방식 | 항목 충족 여부에 치우침 | 현재 상태와 목표 상태 차이를 줄임 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Govern | 사이버보안 위험관리 전략과 정책과 책임을 정하고 감시하는 기능임 |
| Identify | 자산, 업무, 위험, 공급망을 식별해 보호 대상과 우선순위를 정하는 기능임 |
| Protect | 접근 통제, 교육, 데이터 보안, 플랫폼 보호로 피해 가능성을 줄이는 기능임 |
| Detect | 이상 징후와 이벤트를 식별해 빠른 대응을 가능하게 하는 기능임 |
| Respond·Recover | 사고 대응과 복구를 통해 피해를 줄이고 정상 운영으로 되돌리는 기능임 |

```text
Govern -> Identify -> Protect -> Detect -> Respond -> Recover
```

## Ⅴ. 원리 및 절차 흐름도

```text
범위 정의 -> Current Profile 작성 -> Target Profile 설정 -> 차이 분석 -> 개선 실행
```

1. **범위 정의**: 적용할 조직, 서비스, 자산, 규제 범위를 정함
2. **현재 수준 파악**: CSF Core 기준으로 현재 보안 활동과 증적을 정리함
3. **목표 수준 설정**: 사업 목표와 위험 허용 수준에 맞는 Target Profile을 정함
4. **차이 분석**: 현재와 목표 사이의 차이를 우선순위화함
5. **개선 실행**: 투자, 정책, 통제, 훈련을 반영하고 주기적으로 갱신함

## Ⅵ. 실무 적용 및 유의점

1. 경영 보고에는 기술 항목보다 CSF 기능별 현재와 목표 차이를 제시하고 고위험 차이 항목 수와 개선 완료율로 우선순위를 관리함
2. 기존 ISO 27001이나 ISMS-P 조직은 CSF를 별도 체계로 중복 운영하지 말고 통제 매핑률과 중복 증적 수로 통합 운영 수준을 확인함

## Ⅶ. 결론

- NIST CSF는 통제 체크리스트가 아니라 조직의 사이버보안 위험을 공통 언어로 설명하고 개선 우선순위를 정하는 프레임워크임
