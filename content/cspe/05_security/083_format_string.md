## 미리 알고가기

- 포맷 스트링은 `printf("%s", value)`처럼 출력 형식을 지정하는 문자열을 뜻함
- 취약점은 사용자 입력을 데이터가 아니라 포맷 문자열 자체로 해석하게 할 때 발생함
- `%x`는 메모리 읽기, `%n`은 메모리에 값 쓰기와 연결될 수 있어 정보 유출과 흐름 변조가 가능함

## Ⅰ. 개요

- **정의/개념**: 포맷 스트링 공격은 `printf(user_input)` 같은 코드에서 사용자 입력에 포함된 포맷 지정자가 메모리 읽기나 쓰기로 해석돼 정보 유출이나 제어 흐름 변조를 일으키는 공격임
- **배경/필요성**: C 계열 프로그램의 가변 인자 출력 함수는 사용법이 단순해 보이지만 포맷 문자열을 외부 입력과 분리하지 않으면 오래된 레거시 코드에서 치명적 취약점이 반복됨

## Ⅱ. 특징

- 문자열 출력 기능이 메모리 조작 기능으로 바뀌는 점이 핵심임
- 스택 내용 유출과 임의 쓰기가 모두 가능해 다른 방어 우회에 악용될 수 있음
- 정적 분석으로 비교적 잘 찾을 수 있지만 레거시 코드에 잔존하기 쉬움
- 출력 함수 호출 규칙과 RELRO 같은 링크 보호 수준이 실제 위험도를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 읽기형 포맷 스트링 | 쓰기형 포맷 스트링 |
|:---|:---|:---|
| 대표 지정자 | `%x`, `%p`, `%s` | `%n` |
| 주된 목적 | 스택과 주소 정보 유출 | 메모리 값 변조 |
| 대표 피해 | 카나리와 주소 누출 | GOT 등 제어 정보 덮어쓰기 |
| 기본 대응 | 포맷 문자열 상수화 | 포맷 문자열 상수화 + 쓰기 대상 보호 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가변 인자 함수 | `printf`, `sprintf`, `fprintf` 같은 함수임 |
| 외부 입력 | 포맷 문자열로 잘못 사용되는 사용자 데이터임 |
| 메모리 참조 | 포맷 지정자 해석으로 스택이나 전역 주소를 다룸 |
| 방어 기법 | 포맷 상수화, 컴파일 경고, RELRO, 코드 리뷰가 포함됨 |

```text
외부 입력 -> 포맷 문자열로 오인 -> 메모리 읽기/쓰기 발생 -> 정보 유출 또는 흐름 변조
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약 출력 함수 호출 -> 악성 지정자 포함 입력 전달 -> 스택 참조/쓰기 -> 주소 계산 또는 변조 -> 후속 공격
```

1. **취약 호출 존재**: 포맷 문자열이 상수로 고정되지 않은 코드를 찾음
2. **악성 입력 전달**: 지정자를 포함한 문자열을 보냄
3. **메모리 참조**: 함수가 입력을 포맷으로 해석해 값을 읽거나 씀
4. **후속 악용**: 유출된 주소로 ASLR 우회나 제어 정보 변조를 시도함
5. **재검증**: 상수 포맷 적용 후 동일 입력이 단순 문자열로 처리되는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. C 기반 레거시 서비스는 모든 출력 함수를 상수 포맷 규칙으로 통일하고, `-Wformat-security`와 Full RELRO를 함께 적용한 뒤 취약 호출 제거율과 동일 입력 재현 여부와 링크 보호 적용 결과로 확인함
2. 메모리 취약점 점검 환경에서는 포맷 스트링을 단독 문제로 보지 말고 주소 누출 출발점까지 함께 살펴보고 주소 유출 차단 여부와 후속 익스플로잇 체인 실패 여부로 확인함

## Ⅶ. 결론

- 포맷 스트링 공격은 출력 기능의 사용 실수가 메모리 조작으로 바뀌는 문제이므로 포맷 문자열을 상수로 고정하는 규칙이 가장 기본적인 방어임
