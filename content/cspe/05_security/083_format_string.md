## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | `printf(user_input)` 형태로 포맷 문자열을 사용자 입력에서 직접 받을 때, `%x`, `%n` 등을 주입하여 메모리를 읽거나 쓰는 공격임 |
| **배경/필요성** | C 표준 라이브러리의 가변 인자 함수가 인자 개수를 검증하지 않아, 포맷 지정자 오용으로 임의 메모리 접근이 가능함 |
| **출제 의도** | 포맷 스트링 취약점의 원리와 `%n` 기반 임의 쓰기 메커니즘을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 포맷함수  | --> | 포맷지정자| --> | 스택참조  |
| (printf) |     | (%x,%n)  |     | (메모리)  |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 포맷 함수 | `printf`, `sprintf`, `fprintf` 등 가변 인자를 받는 출력 함수임 | 주문서를 읽는 점원 |
| 포맷 지정자 | `%x`(16진수 출력), `%s`(문자열), `%n`(출력 바이트 수 기록) 등 제어 문자임 | 주문서의 특수 지시어 |
| 스택 메모리 | 포맷 지정자가 참조하는 가변 인자 영역으로, 공격자가 스택 내용을 유출·변조함 | 점원이 참조하는 재고 창고 |

> 요약: 포맷 함수가 사용자 입력을 포맷 문자열로 해석하면 스택 메모리 유출·변조가 가능함.

## Ⅲ. 절차
```
+------------+     +------------+
| 취약지점   | --> | %x 반복   |
| 식별       |     | 스택누출   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| GOT 변조   | <-- | %n으로   |
| 흐름탈취   |     | 임의쓰기  |
+------------+     +------------+
```

1. 취약 지점 식별: `printf(buf)` 형태의 포맷 문자열 미지정 코드를 탐색함
2. 스택 내용 유출: `%x`를 반복 입력하여 스택에 저장된 주소·카나리 값을 추출함
3. 쓰기 대상 계산: GOT(Global Offset Table) 엔트리 주소와 목표 함수 주소를 계산함
4. `%n` 임의 쓰기: 출력 바이트 수를 조절하여 `%n`으로 GOT 엔트리를 목표 주소로 덮어씀

> 요약: 스택 유출 → 주소 계산 → `%n` 쓰기 → 실행 흐름 변조 순으로 공격이 진행됨.

## Ⅳ. 문제점
- 레거시 함수 잔존: `printf(buf)` 패턴이 오래된 C 코드베이스에 광범위하게 남아 있음
- 탐지 어려움: 정상적인 문자열 출력과 악성 포맷 입력의 구분이 정적 분석만으로 어려움
- RELRO 미적용: Partial RELRO 환경에서 GOT 영역이 쓰기 가능하여 공격 대상이 됨

## Ⅴ. 개선방안
- (단기) 포맷 문자열 고정: `printf("%s", buf)` 형태로 포맷을 상수 리터럴로 고정함
- (중기) Full RELRO 적용: 링커 옵션으로 GOT 영역을 읽기 전용으로 설정하여 덮어쓰기를 차단함
- (장기) 컴파일러 경고 강화: `-Wformat-security` 플래그 필수 적용 및 CI/CD 파이프라인에서 자동 검출함

## Ⅵ. 전망
- GCC·Clang의 `-Wformat` 경고가 기본 활성화되고, FORTIFY_SOURCE 매크로 적용이 확산되어 신규 코드에서의 발생은 감소 추세이나, 레거시 IoT 펌웨어에서는 여전히 위협임
