## Ⅰ. 개요
- **정의**: 인증(신원 확인) 또는 권한부여(접근 허가) 로직의 결함으로 비인가 접근이 허용되는 취약점
- **배경/필요성**: 세션 관리, 토큰 검증, 접근 제어 로직의 구현 오류가 계정 탈취와 권한 상승의 원인이 됨
- **비유**: 신분증 없이 출입하거나 일반 직원이 사장실 열쇠를 사용할 수 있는 상태와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OWASP 취약점 이해 | 인증 결함과 권한 결함의 구분 | 수평적/수직적 권한 상승 차이 설명 |

> 요약: 인증과 권한부여의 구현 결함이 비인가 접근과 권한 상승을 초래함

## Ⅱ. 구성요소
```text
사용자 --> 인증(Authentication) --> 세션/토큰 발급 --> 권한(Authorization) --> 리소스
              |                                           |
        결함: 약한 비밀번호,                        결함: IDOR, 권한 우회
              세션 고정                                   수직 상승
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 인증 결함 | 약한 비밀번호 정책, 세션 고정, 크리덴셜 스터핑 허용 | 잠금장치 없는 문 |
| 수평적 권한 상승 | 동일 권한 타 사용자의 리소스에 접근(IDOR) | 옆 사람 사물함 열기 |
| 수직적 권한 상승 | 일반 사용자가 관리자 기능에 접근 | 직원이 사장 권한 획득 |

> 요약: 인증 결함과 수평/수직 권한 상승이 주요 공격 유형임

## Ⅲ. 절차
```text
인증 우회 시도 --> 세션/토큰 탈취 --> 권한 검증 우회 --> 비인가 리소스 접근
```
- 1단계: 인증 우회 — 크리덴셜 스터핑, 브루트포스, 기본 계정 등으로 인증을 우회함
- 2단계: 세션 탈취 — 세션 ID 추측, 세션 고정, XSS를 통한 토큰 탈취를 수행함
- 3단계: 권한 우회 — URL 파라미터의 `userId`를 변경(IDOR)하거나 역할 값을 조작함
- 4단계: 비인가 접근 — 타 사용자 데이터 열람, 관리자 기능 실행 등을 수행함

> 요약: 인증 우회-세션 탈취-권한 우회-비인가 접근의 4단계로 공격이 진행됨

## Ⅳ. 문제점
- 계정 탈취: 약한 인증 정책으로 크리덴셜 스터핑이 성공하여 대규모 계정이 장악됨
- IDOR 노출: API에서 객체 참조를 직접 노출하여 타 사용자 데이터에 접근 가능함
- 세션 관리 미흡: 세션 만료, 재사용 방지, 바인딩 미적용으로 세션 하이재킹이 발생함

> 요약: 계정 탈취, IDOR, 세션 관리 미흡이 인증/권한 결함의 주요 위협임

## Ⅴ. 개선방안
1. 단기: MFA 적용과 비밀번호 복잡도 정책을 강화하여 크리덴셜 공격을 차단함
2. 중기: 서버측 권한 검증 로직을 모든 API 엔드포인트에 일관 적용하고 IDOR를 차단함
3. 장기: 세션 바인딩(IP, 디바이스 핑거프린트)과 짧은 만료 시간을 적용하여 세션 탈취를 방지함

> 요약: MFA, 서버측 권한 검증, 세션 바인딩으로 인증/권한 결함을 계층적으로 방어함

## Ⅵ. 전망
- 발전 방향: 패스키(FIDO2) 기반 비밀번호 없는 인증이 확산되어 크리덴셜 공격 표면이 감소할 전망
- 기술사적 판단: API 중심 아키텍처에서 권한 검증의 자동화(OPA 등 정책 엔진)가 표준이 될 것임
- 기술사 제언: 인증과 권한을 분리하여 설계하고, 정책 엔진으로 일관된 접근 제어를 구현해야 함
