# 📖 【암기용】 개념 완전 이해

> 목적: Biba 모델을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 낮은 신뢰도의 정보가 높은 신뢰도 영역을 오염시키지 못하게 막는 무결성 모델
- **왜 필요한가**: 공급망, 회계, 제조, 의료 데이터는 외부 입력이나 검증되지 않은 코드가 핵심 원장을 바꾸면 피해가 크다. 정보의 정확성과 변경 경로를 통제해야 한다.
- **핵심 직관**: 검증 안 된 메모를 공식 장부에 베껴 쓰지 못하게 하고, 공식 장부 담당자가 검증 안 된 게시판 내용을 읽고 판단하지 않게 하는 구조다.

## 깊이 이해
- **배경·문제의식**: Bell-LaPadula는 기밀 유출을 막지만, 낮은 신뢰 데이터가 상위 업무 데이터를 변조하는 문제에는 초점이 다르다. Biba는 무결성 등급으로 오염 흐름을 차단한다.
- **작동 원리**: 높은 무결성 주체는 낮은 무결성 객체를 읽지 못하고(no read down), 낮은 무결성 주체는 높은 무결성 객체에 쓰지 못한다(no write up). Low-watermark는 낮은 데이터를 읽으면 주체 등급을 낮춘다.
- **비유**: 품질검사원이 검증 안 된 부품 목록을 그대로 생산 기준표에 반영하지 못하게 하는 제조 품질 관리와 같다.
- **구체 예시**: 운영 배포 파이프라인에서 인터넷 다운로드 스크립트는 `low integrity`, 서명된 릴리스 아티팩트는 `high integrity`로 두고 low 주체의 high 저장소 쓰기를 차단한다.
- **흔한 오해·주의점**: Biba는 기밀 숨김보다 변조 방지에 집중한다. BLP와 규칙 방향이 반대라는 점을 시험에서 분명히 써야 한다.

## 연결 개념
- Bell-LaPadula — 기밀성 보호 모델, 읽기·쓰기 방향이 Biba와 반대
- Clark-Wilson — 거래·직무분리·감사를 통해 업무 무결성을 보장
- Supply Chain Security — 서명, SBOM, SLSA로 소프트웨어 무결성 적용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: no read down, no write up, low-watermark를 무결성 오염 방지 관점에서 설명하고 BLP와 반대 방향을 명확히 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Biba Integrity Model은 낮은 무결성 데이터가 높은 무결성 객체와 의사결정을 오염시키지 않도록 읽기·쓰기 방향을 제한하는 모델이다.
> 2. **가치**: 공급망, 회계, 배포 파이프라인에서 검증되지 않은 입력이 승인 데이터·릴리스·원장을 변조하는 경로를 차단한다.
> 3. **판단 포인트**: Bell-LaPadula가 기밀성 유출 방지라면 Biba는 무결성 오염 방지이며, no read down과 no write up이 핵심 규칙이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 무결성 모델 이해 확인 | no read down, no write up, integrity level | 기밀성 모델로 설명 |
| BLP와 비교 역량 확인 | 정보흐름 방향 반대, 보호 목표 차이 | no read up/no write down으로 오기 |
| 실무 적용 판단 확인 | 공급망, 데이터 품질, 배포 아티팩트 서명 | 추상적 변조 방지 표현만 사용 |

> 요약: 이 문제는 낮은 신뢰 데이터가 높은 신뢰 자산을 오염시키는 흐름을 어떻게 차단하는지 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 무결성 오염 차단 흐름통제
- 배경: 외부 입력, 검증 전 패키지, 낮은 신뢰 데이터가 기준정보·원장·릴리스 아티팩트로 유입되면 업무 의사결정과 배포물이 오염됨
- 필요성: 공급망·회계·의료·배포 파이프라인은 integrity label 100%, Sigstore/Cosign 서명 검증, no read down·no write up 정책으로 변조 경로를 차단해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Subject -> Integrity Level 비교 -> Object 접근 결정
            / Read: no read down
            / Write: no write up
            / Low-watermark: 등급 하향
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Subject | 데이터를 읽고 쓰는 사용자·프로세스 | 빌드 서버, 승인자, 업무 시스템 |
| Object | 보호 대상 데이터·파일·아티팩트 | 원장, 릴리스 파일, 기준정보 |
| Integrity Level | High, Medium, Low 등 신뢰 등급 | 서명·검증 상태와 연계 |
| Simple Integrity Axiom | 낮은 무결성 객체 읽기 금지 | no read down |
| Star Integrity Axiom | 높은 무결성 객체 쓰기 금지 | no write up |
| Low-watermark | 낮은 데이터를 읽은 주체 등급 하향 | 오염 전파 추적 |

> 요약: Biba는 주체와 객체의 무결성 등급을 비교해 낮은 신뢰 입력의 읽기·쓰기 경로를 제한한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접근 요청 -> Subject integrity 확인 -> Object integrity 확인
-> Read/Write 구분 -> Biba 규칙 적용 -> 허용/거부 또는 등급 하향
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 주체 무결성 등급 확인 | 빌드·운영 계정 등급 라벨 100% |
| 2 | 객체 무결성 등급 확인 | 서명·해시 검증 결과 기록 |
| 3 | 읽기 요청이면 no read down 적용 | high 주체의 low 데이터 읽기 차단 |
| 4 | 쓰기 요청이면 no write up 적용 | low 주체의 high 객체 쓰기 차단 |
| 5 | low-watermark 적용 시 등급 변경 기록 | 등급 하향 로그 1년 보관 |

> 요약: Biba는 읽기·쓰기 요청마다 무결성 등급을 비교하고, 필요 시 주체 등급을 낮춰 오염 전파를 추적한다.

---

## Ⅳ. 특징

| 구분 | Bell-LaPadula | Biba | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 보호 목표 | 기밀성 유출 방지 | 무결성 오염 방지 | 공급망·회계·배포 데이터 |
| 읽기 규칙 | no read up | no read down | high 주체가 low 데이터 읽기 금지 |
| 쓰기 규칙 | no write down | no write up | low 주체가 high 객체 쓰기 금지 |
| 실무 예 | 군사 기밀 | 서명 릴리스, 기준정보 | SHA-256, Sigstore, SLSA |

> 요약: Biba는 Bell-LaPadula와 규칙 방향이 반대이며, 핵심 목적은 낮은 신뢰 입력의 상위 데이터 오염 차단이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | ACL 기반 쓰기 제한 | 무결성 등급 기반 흐름 통제 | 데이터 신뢰도 차이가 업무 결과를 좌우할 때 |
| 비용/성능 | 라벨·서명 관리 없음 | 해시·서명·등급 라벨 필요 | 릴리스 아티팩트 100% 서명 가능 여부 |
| 운영/위험 | 외부 입력 검증 누락 | low 데이터 오염 경로 차단 | 공급망·ETL·원장 변경 업무 |

> 요약: 외부 입력과 내부 기준정보가 섞이는 환경에서는 ACL보다 무결성 등급과 서명 검증이 필요한 판단 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 등급 오분류 | 데이터 출처·검증 상태 누락 | 데이터 카탈로그, 해시·서명 검증 | 미분류 객체 0건 |
| 업무 차단 | high 사용자의 low 데이터 분석 제한 | 격리 분석 영역, 등급 하향 승인 | 승인 건수, 처리 시간 |
| 공급망 변조 | 외부 패키지·빌드 스크립트 오염 | SBOM, SLSA, Sigstore 서명 | 서명 검증 실패율 |

> 요약: 실무 리스크는 등급 오분류, 업무 차단, 공급망 변조이며 카탈로그와 서명 검증으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 무결성 라벨 | 주요 데이터·아티팩트 라벨 100% | 데이터 카탈로그, CI/CD 메타데이터 |
| 서명 검증 | 릴리스 아티팩트 100% 서명 | Sigstore, Cosign, SHA-256 |
| 변조 탐지 | 기준정보 변경 100% 승인·감사 | DB 감사로그, 변경관리 시스템 |

> 요약: 도입 성과는 라벨 완전성, 서명 검증률, 기준정보 변경 감사율로 측정한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 데이터 등급화: 기준정보, 원장, 릴리스 아티팩트를 high integrity로 지정하고 외부 입력·임시 파일은 low integrity로 분리
2. 배포 통제: SBOM, SLSA Level 3, Sigstore/Cosign 서명을 적용하고 서명 실패 아티팩트는 배포 게이트에서 차단
3. 운영 감사: 기준정보 변경은 2인 승인, DB 감사로그, 해시 비교를 적용하고 low-watermark 이벤트를 SIEM에 전송

**결론 (2줄):**
- 기술사 판단: 데이터 정확성과 공급망 신뢰가 핵심인 시스템은 Biba 기반 무결성 등급과 서명 검증을 함께 적용함
- 향후 방향: 데이터 카탈로그, SBOM, 정책 코드화로 무결성 등급과 배포 검증을 자동 연결함
