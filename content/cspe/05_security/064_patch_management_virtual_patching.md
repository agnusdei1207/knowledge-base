## 미리 알고가기

- 패치 관리는 취약점 수정본을 평가하고 배포하고 재검증하는 운영 체계이며, 가상 패치는 정식 패치 전후에 공격 경로를 임시 차단하는 보상 통제임
- 가상 패치는 정식 패치의 대체물이 아니라 노출 시간을 줄이는 임시 수단임
- 핵심은 취약점 위험과 운영 변경 위험을 함께 관리하는 데 있음

## Ⅰ. 개요

- **정의/개념**: 패치 관리는 취약점 영향 자산을 식별해 수정본 적용과 재검증을 관리하고, 가상 패치는 악용 경로를 임시 차단함
- **배경/필요성**: 취약점 공개 후 공격은 빠르게 확산되지만 운영 시스템은 테스트와 변경 승인이 필요함. 정식 패치 전 공백을 줄여야 함

## Ⅱ. 특징

- 패치 관리는 자산 중요도, 서비스 영향, SLA로 우선순위를 운영함
- 가상 패치는 긴급 차단 효과가 있으나 우회 가능성과 범위 한계가 있음
- 재부팅과 호환성 문제를 고려한 테스트와 롤백 계획이 필요함
- 예외 승인과 만료일 관리가 없으면 미적용 취약점이 장기 누적됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 정식 패치 | 가상 패치 |
|:---|:---|:---|
| 목적 | 취약점 원인을 제거 | 악용 경로를 임시 차단 |
| 적용 위치 | OS, 애플리케이션, 라이브러리 자체 | WAF, IPS, 프록시, 설정 계층 |
| 장점 | 근본 원인 해결 | 빠른 적용과 운영 연속성 확보 |
| 한계 | 테스트와 배포 시간이 필요함 | 우회 가능, 범위 제한, 만료 관리 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 영향 자산 식별 | CVE, 버전, 노출 여부를 바탕으로 대상 시스템을 찾음 |
| 우선순위와 승인 | 심각도와 서비스 영향과 변경 윈도우를 반영해 배포 계획을 정함 |
| 정식 패치 적용 | 테스트, 단계 배포, 롤백 계획으로 수정본을 반영함 |
| 가상 패치 및 재검증 | 차단 룰과 우회 통제를 적용하고 효과를 다시 확인함 |

```text
취약점 확인 -> 영향 자산 식별 -> 우선순위/SLA 결정 -> 가상 패치 또는 정식 패치 -> 재점검
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약점 접수 -> 자산 매핑 -> 긴급도 판단 -> 임시 차단 -> 테스트/배포 -> 재스캔/롤백 확인
```

1. **취약점 접수**: 벤더 권고와 스캐너 결과와 내부 제보를 수집함
2. **자산 매핑**: 영향 버전과 인터넷 노출과 업무 중요도를 확인함
3. **긴급도 판단**: 패치 기한과 예외 승인 여부를 정함
4. **임시 차단**: 필요 시 WAF·IPS 룰이나 설정 변경을 먼저 적용함
5. **정식 배포와 재검증**: 패치를 반영하고 재스캔과 서비스 정상 동작을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 인터넷 노출 웹 서비스는 가상 패치로 공격 경로를 먼저 막고 실제 공격 재현 실패·서비스 오류 미발생으로 확인함
2. 즉시 패치가 어려운 설비·레거시는 예외 승인, 만료일, 보완 통제를 문서화하고 미적용 자산 최신성·재평가 완료율로 확인함

## Ⅶ. 결론

- 패치 관리와 가상 패치는 공백 시간을 줄이는 연속 절차이므로 정식 수정, 임시 차단, 재검증을 함께 운영해야 함
