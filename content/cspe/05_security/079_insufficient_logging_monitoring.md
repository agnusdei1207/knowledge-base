## 미리 알고가기

- 운영 로그는 시스템 동작 기록이고, 감사 로그는 인증과 권한 변경과 데이터 조회처럼 추적이 필요한 보안 행위 기록임
- 로깅 부족 문제는 로그 저장량이 적다는 뜻보다 침해 탐지와 사후 조사에 필요한 사건 기록이 빠졌다는 뜻에 가깝음
- 보안 관제 시스템(SIEM)은 여러 시스템의 로그를 모아 규칙 기반으로 분석하고 경보를 만드는 체계임
- 평균 탐지 시간(MTTD)과 평균 복구 시간(MTTR)은 탐지와 대응 속도를 보는 대표 지표임
- 모니터링은 단순 대시보드가 아니라 경보 기준과 대응 절차까지 연결돼야 의미가 있음

## Ⅰ. 개요

- **정의/개념**: 로깅·모니터링 불충분은 중요 보안 이벤트가 기록, 중앙 분석, 경보, 대응 절차에 연결되지 않은 상태임
- **배경/필요성**: 공격은 로그인 실패, 권한 상승, 대량 조회, 정책 변경 흔적을 남김. 핵심 이벤트가 없으면 사고 추적이 어려움

## Ⅱ. 특징

- 에러 로그만 있고 인증·권한·관리 행위 로그가 없으면 불충분함
- 시간 동기화와 무결성 보관이 없으면 로그를 증적으로 쓰기 어려움
- 중앙 수집과 상관분석이 없으면 공격 흐름을 보기 어려움
- 저장량보다 탐지 규칙과 대응 담당자 연결이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 운영 로그 | 보안 감사 로그 |
|:---|:---|:---|
| 주목적 | 장애와 성능 확인 | 침해 탐지와 추적 |
| 대표 항목 | 상태 메시지, 오류, 자원 사용량 | 로그인 성공·실패, 권한 변경, 데이터 반출 |
| 보존 요구 | 운영 효율 중심 | 무결성, 보존 기간, 증적 활용이 중요함 |
| 미비 시 영향 | 장애 분석 지연 | 침해 탐지 실패와 책임 추적 불가 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 기준 | 어떤 행위를 감사 로그로 남길지 정의함 |
| 중앙 수집 | 여러 시스템의 로그를 한곳으로 모음 |
| 분석과 경보 | 상관분석과 임계값으로 이상 징후를 탐지함 |
| 대응 연계 | 경보를 조사와 차단과 티켓으로 연결함 |

```text
이벤트 정의 -> 로그 수집 -> 중앙 분석 -> 경보 생성 -> 조사/대응 -> 보완
```

## Ⅴ. 원리 및 절차 흐름도

```text
보안 이벤트 발생 -> 로그 기록 -> 중앙 전송 -> 상관분석 -> 경보/티켓 -> 조치와 회고
```

1. **이벤트 정의**: 인증, 권한, 관리 작업, 데이터 반출 이벤트를 정함
2. **로그 기록과 전송**: 각 시스템이 일관된 형식으로 중앙 저장소에 보냄
3. **상관분석**: 개별 이벤트를 묶어 이상 징후를 식별함
4. **경보와 대응**: 우선순위에 따라 조사와 차단을 수행함
5. **회고와 보완**: 빠진 이벤트와 과한 경보를 조정함

## Ⅵ. 실무 적용 및 유의점

1. 외부 사용자·관리자 서비스는 로그인 실패, 권한 변경, 대량 반출을 감사 이벤트로 고정하고 MTTD·MTTR·로그 누락률로 확인함
2. 로그 보관 체계는 무결성과 NTP 기반 시간 동기화를 점검하고 타임라인 재구성 가능 여부·로그 변조 탐지 결과로 확인함

## Ⅶ. 결론

- 로깅·모니터링 불충분은 저장량보다 탐지와 조사에 필요한 사건 기록과 대응 연결을 확보하는 문제임
