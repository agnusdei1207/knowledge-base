## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 멀티 클라우드 환경에서 사용자·서비스 계정·역할의 과도한 권한(Over-Privilege)을 탐지하고 최소 권한으로 최적화하는 ID 권한 관리 솔루션임 |
| **배경/필요성** | 클라우드 IAM의 권한 조합이 수만 개에 달하며, 미사용·과도 권한이 공격면을 확대하므로 권한의 지속적 최적화가 필수임 |
| **출제 의도** | CIEM의 권한 분석 메커니즘과 IAM·PAM과의 역할 구분을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 권한수집  | --> | 사용분석  | --> | 최적화   |
| (Inventory)|   | (Gap분석) |     | (Rightsizing)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 권한 인벤토리 | 멀티 클라우드의 모든 ID·역할·정책을 수집·정규화함 | 전 직원 출입 권한 명부 |
| 사용 분석 | 실제 API 호출 로그(CloudTrail 등)와 부여 권한을 대조하여 미사용 권한을 식별함 | 출입 기록 vs 발급 카드 비교 |
| 권한 최적화 | 미사용·과도 권한을 제거하고 최소 권한 정책을 자동 추천·적용함 | 불필요한 출입 카드 회수 |

> 요약: 권한 수집 → 사용 분석(Gap 탐지) → 최적화(Rightsizing)로 클라우드 권한을 최소화함.

## Ⅲ. 절차
```
+------------+     +------------+
| 멀티클라우드| --> | 권한·로그  |
| IAM수집    |     | 대조분석   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 정책적용   | <-- | 최소권한  |
| 모니터링   |     | 정책추천   |
+------------+     +------------+
```

1. IAM 수집: AWS·Azure·GCP의 IAM 정책·역할·서비스 계정을 API로 수집·정규화함
2. 권한·로그 대조: CloudTrail·Activity Log에서 실제 사용된 권한과 부여된 권한을 대조 분석함
3. 최소 권한 정책 추천: 미사용 권한을 제거하고 실제 사용 패턴 기반 최적 정책을 자동 생성함
4. 정책 적용·모니터링: 추천 정책을 적용하고, 지속 모니터링으로 권한 드리프트를 탐지함

> 요약: 수집 → 대조 분석 → 최적화 추천 → 적용·모니터링으로 멀티 클라우드 권한을 통제함.

## Ⅳ. 문제점
- 서비스 계정 폭증: IaC·CI/CD 자동화로 서비스 계정이 급증하여 추적이 어려움
- 권한 추천 정확성: ML 기반 추천이 비정기 작업의 권한을 오제거하여 장애를 유발할 수 있음
- 멀티 클라우드 정규화: CSP별 IAM 모델(AWS IAM vs Azure RBAC vs GCP IAM)이 상이하여 통합이 복잡함

## Ⅴ. 개선방안
- (단기) 시뮬레이션 모드: 권한 제거 전 시뮬레이션으로 영향을 사전 평가함
- (중기) JIT 접근 연동: CIEM과 PAM을 연동하여 과도 권한 대신 필요 시 JIT 발급으로 전환함
- (장기) CNAPP 통합: CIEM을 CSPM·CWPP와 통합하여 권한·설정·워크로드를 상관 분석함

## Ⅵ. 전망
- 멀티 클라우드 환경에서 CIEM이 IAM 거버넌스의 핵심 도구로 부상하며, CNAPP 내에서 공격 경로 분석(권한 기반 측면 이동)의 핵심 데이터를 제공할 전망임
