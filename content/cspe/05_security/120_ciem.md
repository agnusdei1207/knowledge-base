## 미리 알고가기

- 엔타이틀먼트는 사용자나 서비스 계정에 부여된 권한 묶음을 뜻함
- 최소 권한은 업무에 필요한 권한만 주고 나머지는 제거하는 원칙임
- 서비스 계정은 사람이 아닌 애플리케이션이나 자동화 작업이 쓰는 계정임

## Ⅰ. 개요

- **정의/개념**: CIEM은 멀티 클라우드 환경의 사용자, 역할, 서비스 계정 권한을 수집해 실제 사용 이력과 비교하고 과도 권한을 최소 권한 수준으로 줄이는 권한 관리 체계임
- **배경/필요성**: 클라우드 IAM은 역할 조합과 위임 경로가 복잡해 권한이 한 번 넓어지면 장기간 남기 쉬우므로 부여 권한과 사용 권한의 차이를 계속 점검할 필요가 커짐

## Ⅱ. 특징

- 사람 계정뿐 아니라 서비스 계정과 역할 위임 관계까지 함께 분석함
- 실제 API 사용 로그를 바탕으로 미사용 권한과 과도 권한을 찾음
- 단일 권한이 아니라 권한 조합이 만드는 우회 경로와 상승 경로까지 봄
- 단순 회수보다 업무 영향 없는 권한 축소가 중요하므로 승인 흐름이 함께 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | IAM | PAM | CIEM |
|:---|:---|:---|:---|
| 주된 관심사 | 계정과 역할의 기본 관리 | 특권 계정 통제와 세션 감사 | 클라우드 과도 권한 분석과 축소 |
| 보는 대상 | 사용자와 역할 정책 | 관리자 계정과 고권한 작업 | 사용자, 역할, 서비스 계정, 위임 경로 |
| 핵심 기능 | 권한 부여와 인증 연계 | 승인, 금고, 기록 | 사용 로그 기반 권한 최적화 |
| 필요한 이유 | 기본 접근 체계 | 특권 오남용 억제 | 클라우드 권한 누적 억제 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 권한 인벤토리 | 멀티 클라우드의 사용자, 역할, 정책, 위임 관계를 모음 |
| 사용 분석 | CloudTrail 같은 로그로 실제 사용한 API와 미사용 권한을 구분함 |
| 위험 분석 | 관리자 권한, 와일드카드 정책, 상승 경로를 찾아 위험도를 매김 |
| 권한 최적화 | 제거 가능한 권한과 더 좁은 정책을 추천하거나 자동 반영함 |
| 승인·감사 | 운영 영향 검토와 변경 이력을 남겨 회수 실패를 줄임 |

```text
권한 수집 -> 사용 로그 대조 -> 과도 권한 식별 -> 축소안 제시/승인 -> 정책 반영 -> 재검증
```

## Ⅴ. 원리 및 절차 흐름도

```text
계정과 정책 수집 -> 실제 사용 이력 분석 -> 미사용·과도 권한 식별 -> 권한 축소 적용 -> 업무 영향 확인
```

1. **권한 수집**: 사용자, 역할, 서비스 계정 정책을 정규화해 모음
2. **사용 이력 분석**: 실제 호출한 API와 부여된 권한을 비교함
3. **위험 식별**: 관리자 권한, 와일드카드, 상승 경로를 찾음
4. **권한 축소**: 제거 가능한 권한을 승인 후 반영함
5. **영향 확인**: 정상 업무가 깨지지 않았는지 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 장기간 쓰이는 서비스 계정은 권한이 넓어지기 쉬우므로 사용 로그를 기준으로 축소하고 미사용 권한 비율과 고권한 계정 수와 권한 축소 뒤 장애 건수로 확인함
2. 멀티 클라우드에서는 같은 이름의 역할도 의미가 다를 수 있으므로 권한 모델을 먼저 정규화하고 위험한 위임 경로 수와 금지 권한 조합 수로 점검함

## Ⅶ. 결론

- CIEM은 권한을 더 많이 주는 관리가 아니라 실제로 쓰는 권한만 남기는 관리이므로 로그 기반 분석과 안전한 권한 축소 절차가 핵심임
