# 📖 【암기용】 개념 완전 이해

> 목적: CIEM을 처음 보는 사람도 클라우드 권한 과다가 왜 위험하고 어떻게 줄이는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: CIEM은 클라우드 사용자, 역할, 서비스 계정의 권한을 분석하고 최소 권한으로 조정하는 관리 체계임
- **왜 필요한가**: 클라우드 IAM은 사용자, Role, Policy, 서비스 계정, Cross Account 신뢰가 복잡하게 연결된다. 실제 사용하지 않는 권한이 남으면 계정 탈취 시 데이터 삭제, 키 생성, 권한 상승으로 이어진다.
- **핵심 직관**: 회사 출입카드가 사무실, 금고, 서버실, 외부 창고까지 열 수 있는지 조사하고 실제 사용 문만 남기는 권한 정리 작업임

## 깊이 이해
- **배경·문제의식**: 클라우드는 운영 자동화를 위해 넓은 권한을 임시로 부여한 뒤 회수하지 않는 일이 많다. Managed Policy, Wildcard 권한, 장기 Access Key, Cross Account Role이 쌓이면 권한 경로를 사람이 추적하기 어렵다.
- **작동 원리**: CIEM은 IAM 정책, 그룹, Role, 서비스 계정, 리소스 정책, 사용 로그를 수집한다. 실제 사용 권한과 부여 권한을 비교해 과도 권한, 미사용 권한, 권한 상승 경로, 외부 신뢰 관계를 찾아 축소 권고와 자동 조치를 수행한다.
- **비유**: 병원 직원 출입기록을 90일 동안 분석해 사용하지 않은 수술실·약품창고 권한을 회수하고 야간 출입은 승인제로 바꾸는 방식임
- **구체 예시**: 개발 Role이 `s3:*`, `iam:PassRole`, `kms:*`를 보유하지만 90일 동안 `s3:GetObject`만 사용했다면 읽기 권한으로 축소하고 `iam:PassRole`은 제거함
- **흔한 오해·주의점**: CIEM은 IAM 관리 화면과 다르다. 단순 권한 목록이 아니라 실제 사용량, 리소스 민감도, 권한 상승 경로, 외부 계정 신뢰까지 그래프로 분석해야 함

## 연결 개념
- IAM/PAM — 신원·특권 접근 관리의 기반
- 최소 권한 원칙 — 필요한 권한만 필요한 기간 부여
- CNAPP — CIEM 결과를 형상·워크로드 위험과 결합

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CIEM은 클라우드 IAM 목록 관리가 아니라 권한 사용량과 권한 경로를 분석해 최소 권한을 지속 적용하는 체계로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CIEM(Cloud Infrastructure Entitlement Management)은 클라우드 신원과 권한을 분석하여 과도 권한과 권한 상승 경로를 줄이는 관리 체계이다.
> 2. **가치**: 미사용 권한, Wildcard Policy, 장기 Access Key, Cross Account Trust를 식별해 계정 탈취 시 피해 범위를 제한한다.
> 3. **판단 포인트**: 부여 권한과 실제 사용 권한의 차이, 고위험 권한, 자동 권한 축소, 예외 승인 지표를 제시해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 IAM 위험 이해 확인 | 과도 권한, 미사용 권한, 권한 상승, Cross Account | RBAC 설명으로만 축소 |
| 최소 권한 운영 역량 확인 | 사용량 분석, 권한 축소, Access Key 관리, JIT | 계정 생성·삭제 절차만 서술 |
| 지표 기반 관리 확인 | 권한 사용률, Wildcard 0건, Key 회전, 예외 만료 | 제품명 나열 후 정량 기준 부재 |

> 요약: CIEM 답안은 권한 목록이 아니라 사용량 기반 최소 권한과 권한 경로 통제를 중심으로 구성해야 한다.

---

## Ⅰ. 개요 및 필요성

CIEM은 클라우드 권한 최소화 관리 체계이다.
클라우드 IAM은 사용자, Role, 서비스 계정, 리소스 정책, 외부 신뢰가 얽혀 과도 권한과 권한 상승 경로가 생기기 쉽다.
따라서 부여 권한과 실제 사용 권한을 비교하고 미사용·고위험 권한을 지속 회수해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Cloud IAM/Logs -> Entitlement Collector -> Permission Graph
  / Users, Roles, Service Accounts
  / Policies, Resource Permissions, Trust Relationships
Permission Graph -> Risk Analysis -> Right-Sizing/JIT -> Evidence
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Entitlement Collector | IAM 정책, Role, 그룹, 리소스 권한 수집 | AWS IAM, Azure RBAC, GCP IAM |
| Usage Analyzer | 실제 API 호출과 권한 사용량 분석 | CloudTrail, Activity Log, Audit Log |
| Permission Graph | 신원, 권한, 리소스, 신뢰 관계 시각화 | 권한 상승 경로 탐지 |
| Risk Scoring | Wildcard, Admin, PassRole, Key 위험 평가 | 민감 리소스 접근 가중치 |
| Remediation | 권한 축소, JIT, Access Key 회전, 예외 승인 | 승인 워크플로와 롤백 필요 |

> 요약: CIEM은 IAM 권한과 실제 사용 로그를 권한 그래프로 결합해 과도 권한을 식별하고 축소한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
IAM 정책 수집 -> 사용 로그 분석 -> 권한 그래프 생성
-> 과도/미사용/고위험 권한 탐지 -> 권한 축소/JIT 적용
-> 예외 만료/감사 증적
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자, Role, 서비스 계정, 리소스 정책 수집 | 계정 커버리지 100%, 일 1회 이상 수집 |
| 2 | API 호출 로그로 실제 사용 권한 분석 | 분석 기간 90일, 로그 누락 0건 |
| 3 | 권한 그래프와 위험 점수 산정 | Admin, Wildcard, PassRole, 외부 신뢰 표시 |
| 4 | 권한 축소, JIT, Key 회전 실행 | 미사용 권한 30일 이내 회수 |
| 5 | 예외 승인, 만료, 감사 증적 보존 | 예외 만료 90일 이하, 증적 1년 보존 |

> 요약: CIEM은 권한 수집, 사용량 분석, 위험 경로 산정, 권한 축소, 예외 관리 순서로 운영된다.

## Ⅳ. 특징

| 구분 | 전통 IAM 관리 | CIEM | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 분석 기준 | 부여 권한 목록 | 부여 권한과 실제 사용 권한 비교 | 90일 미사용 권한 회수 |
| 대상 | 사용자·그룹 중심 | Role, 서비스 계정, 리소스 정책, 외부 신뢰 | Machine Identity 포함 |
| 위험 분석 | 관리자 권한 여부 | 권한 상승 경로와 민감 리소스 접근 | Wildcard Policy 0건 목표 |
| 운영 방식 | 정기 권한 검토 | 지속 분석과 권한 Right-Sizing | JIT 특권 세션 4시간 이하 |

> 요약: CIEM은 사람 계정뿐 아니라 기계 신원과 외부 신뢰까지 포함해 실제 사용량 기준으로 권한을 줄인다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | IAM 콘솔·수동 리뷰 | 권한 그래프와 사용량 분석 | 멀티클라우드, 서비스 계정 100개 이상 |
| 비용/운영 | 분기 권한 검토 | 지속 권한 축소와 JIT | 권한 변경 빈도 높고 감사 요구 존재 |
| 위험 | 미사용 권한 장기 잔존 | 과도 권한과 권한 상승 경로 탐지 | Admin, Wildcard, 외부 신뢰 우선 |

> 요약: CIEM은 클라우드 권한 수와 기계 신원이 늘어 수동 리뷰로 최소 권한 유지가 어려울 때 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 장애 | 사용량 기간이 짧아 필요한 권한 회수 | 90일 로그 분석, Dry-run, 롤백 정책 | 권한 축소 후 장애 1% 이하 |
| 외부 신뢰 방치 | Cross Account Role, SaaS 연동 권한 누락 | 외부 Principal 목록화, 만료일 설정 | 만료 없는 외부 신뢰 0건 |
| 장기 키 유출 | Access Key 회전·폐기 미흡 | Key 수명 90일, 미사용 Key 폐기 | 90일 초과 Key 0건 |

> 요약: CIEM 운영 리스크는 권한 축소 장애, 외부 신뢰 방치, 장기 키 유출이며 분석 기간과 만료 정책으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 최소 권한 | 90일 미사용 권한 0건 | CIEM 사용량 분석 |
| 고위험 권한 | Wildcard Policy 0건, Admin Role 월 1회 리뷰 | IAM 정책 스캔 |
| 키·예외 | Access Key 90일 이하, 예외 만료 90일 이하 | CSP 로그, 티켓 |

> 요약: CIEM 성과는 미사용 권한 회수, 고위험 정책 제거, 키·예외 만료 준수로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AWS IAM, Azure RBAC, GCP IAM과 CloudTrail, Activity Log, Audit Log를 연동해 90일 사용량 기준 권한 분석을 수행함
2. Wildcard Policy, Admin Role, `iam:PassRole`, Cross Account Trust, 장기 Access Key를 고위험으로 분류하고 미사용 권한은 30일 이내 회수함
3. 특권 작업은 JIT 4시간 이하, MFA 필수, 티켓 승인 기반으로 운영하고 예외 권한은 만료 90일 이하로 관리함

**결론 (2줄):**
- 기술사 판단: 사람 계정보다 서비스 계정과 Role이 많은 클라우드에서는 PAM만으로 부족하므로 CIEM 기반 권한 그래프 분석이 필요함
- 향후 방향: CIEM은 CNAPP 위험 그래프와 결합되어 과도 권한, 취약 워크로드, 인터넷 노출을 하나의 공격 경로로 평가함
