# 📖 【암기용】 개념 완전 이해

> 목적: QKD 양자 키 분배를 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 양자 상태 측정 교란을 이용해 대칭키 재료를 분배하는 물리 계층 기술
- **왜 필요한가**: 장기 기밀 데이터를 보호하려면 키 분배 과정에서 도청 시도와 오류율(QBER)을 식별해야 한다. QKD는 전용 광 링크에서 광자 상태 변화를 확인해 도청 가능성을 판단하고 키를 폐기한다.
- **핵심 직관**: 봉투를 열면 흔적이 남는 편지를 주고받아, 흔적이 없는 일부 비트만 비밀키로 남기는 방식이다.

## 깊이 이해
- **배경·문제의식**: RSA/ECC 키 교환은 수학 난제에 의존하지만 QKD는 양자 측정 교란과 고전 인증 채널을 결합한다. 다만 QKD는 메시지 암호화가 아니라 키 재료 분배 기술이며 전용 광섬유, 장비, 거리 제약이 있다.
- **작동 원리**: 송신자는 단일 광자 또는 약한 레이저 펄스에 비트를 인코딩하고, 수신자는 무작위 기저로 측정한다. 공개 채널에서 기저를 비교하고 QBER가 임계값 이하면 오류 정정과 privacy amplification으로 최종 키를 만든다.
- **비유**: 색안경 각도를 맞춰 봐야 읽히는 카드 묶음이다. 누군가 중간에서 읽으면 카드 상태가 흔들려 오류율이 올라간다.
- **구체 예시**: 광섬유 QKD는 수십~수백 km 구간에 적용하며, 장거리 네트워크는 trusted node 또는 위성 QKD가 필요하다. 키율은 거리와 손실에 따라 kbps~Mbps 범위로 달라진다.
- **흔한 오해·주의점**: QKD만으로 인증은 해결되지 않는다. 최초 인증에는 사전 공유키, PKI, PQC 서명이 필요하며 trusted node는 노드 내부자 위협을 별도로 통제해야 한다.

## 연결 개념
- PQC — 소프트웨어 기반 양자내성 암호 전환 대안
- AES-256 — QKD로 만든 키 재료가 투입되는 대칭키 암호
- ITU-T Y.3800/Y.3803 — QKD 네트워크 구조·키 관리 표준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: QKD는 양자 채널과 인증된 고전 채널을 이용해 대칭키 재료를 분배하는 물리 계층 키 분배 기술임.
> 2. **가치**: 도청 시 QBER 상승을 탐지하여 키 폐기·재생성을 수행하고, AES-256·OTP 등 대칭키 보호에 키 재료를 제공함.
> 3. **판단 포인트**: 광 링크 거리, key rate, QBER, trusted node, 인증 채널, 운영비를 PQC와 비교해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| QKD 원리 이해 | 양자 채널, 고전 인증 채널, QBER, privacy amplification | QKD를 데이터 암호화로 설명 금지 |
| 보안 통제 판단 | 도청 탐지, 키 폐기, 인증 필요 | 인증·무결성 문제를 QKD 단독 해결로 서술 금지 |
| 적용성 비교 | 전용 광섬유, 거리, 키율, trusted node | PQC와 비용·운영 조건 비교 누락 금지 |

> 요약: QKD 답안은 키 분배 원리와 물리 인프라 제약, PQC 대비 선택 기준을 함께 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 양자 채널 기반 키 분배
- 배경: 장기 기밀 통신은 키 교환 과정의 도청과 미래 양자컴퓨터 공격을 함께 고려해야 하며, 공개키 기반 합의만으로는 HNDL 위험이 남음.
- 필요성: QKD는 BB84 계열 양자 채널의 측정 교란과 인증된 고전 채널을 이용해 최종 대칭키 재료를 합의함.

---

## Ⅱ. 구조 및 구성요소

```text
Alice QKD Module -> Quantum Channel -> Bob QKD Module
Alice/Bob -> Authenticated Classical Channel -> Sifting/Error Correction
/ Privacy Amplification -> Key Manager -> AES/OTP Application
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Quantum channel | 광자 상태 전송 | 전용 광섬유, free-space, 위성 링크 |
| Classical channel | 기저 비교·오류 정정·인증 | MAC, PKI, PQC 서명 필요 |
| QBER monitor | 도청·잡음 판단 | 임계값 초과 시 키 폐기 |
| Key manager | 최종 키 저장·공급 | ITU-T Y.3803, 애플리케이션 연계 |

> 요약: QKD는 양자 채널, 인증된 고전 채널, QBER 감시, 키 관리자가 결합된 키 분배 인프라임.

---

## Ⅲ. 동작원리 및 흐름도

```text
광자 인코딩 -> 양자 채널 전송 -> 무작위 기저 측정
-> 기저 공개 비교 -> QBER 산정
-> 오류 정정 -> privacy amplification -> 키 공급
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 광자 상태에 비트 인코딩 | 송신 세기, detector calibration |
| 2 | 수신 기저 측정 | sifted key 생성률 |
| 3 | 공개 채널로 기저 비교 | 인증 MAC 검증 성공 |
| 4 | QBER 계산·키 폐기 판단 | 임계값 초과 시 discard |
| 5 | 오류 정정·privacy amplification | final key rate, 키 무작위성 |

> 요약: QKD는 측정 결과를 공개 비교하고 QBER가 허용 범위일 때만 오류 정정과 privacy amplification으로 최종 키를 생성함.

## Ⅳ. 특징

| 구분 | PQC | QKD | 판단 포인트 |
|:---|:---|:---|:---|
| 구현 방식 | 소프트웨어·프로토콜 교체 | 전용 광 링크·장비 | CAPEX/OPEX, 설치 기간 |
| 보안 근거 | 수학 난제 | 양자 측정 교란 | 인증 채널 별도 필요 |
| 거리·확장 | 인터넷 전 구간 적용 | 수십~수백 km 광 링크 | trusted node·위성 필요 |
| 운영 지표 | handshake p95, KAT | key rate, QBER, link availability | 키 수요 대비 공급량 |

> 요약: QKD는 물리 인프라 비용을 감수하고 링크 단위 키 분배를 제공하므로 PQC와 적용 범위가 다름.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|

| 비용/성능 | 소프트웨어 업데이트 | QKD 장비·광 회선 비용 | 키율 kbps~Mbps와 트래픽 수요 |
| 운영/위험 | 알고리즘 취약점 | 장비·trusted node 위험 | 물리 보안과 NOC 운영 역량 |

> 요약: QKD는 전용 회선과 물리 보안 운영이 가능한 금융·국방·데이터센터 간 링크에 제한 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 인증 부재 | 고전 채널 위조 | PQC 서명 또는 사전 공유 MAC | 인증 실패 차단률 100% |
| trusted node 노출 | 중간 노드에 키 평문 존재 | HSM, 출입통제, dual control | 노드 감사 위반 0건 |
| 키율 부족 | 거리 손실·검출기 잡음 | 링크 예산 설계, 키 버퍼링 | key starvation 0건 |

> 요약: QKD 운영 위험은 인증 채널, trusted node, 키율 부족이며 물리·논리 통제를 함께 적용함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 링크 품질 | QBER 임계값 이하, link availability 99.9% | QKD NMS, 광 파워 측정 |
| 키 공급 | 애플리케이션 키 수요 대비 120% 버퍼 | key manager 로그 |
| 보안 운영 | 장비 tamper, 출입통제, 감사로그 | SIEM 연계, 정기 점검 |

> 요약: QKD 도입 효과는 QBER, key rate, link availability, 물리 보안 감사 지표로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 데이터센터 간 100km급 전용 광 링크를 대상으로 link budget, QBER, key rate를 PoC로 측정하고 AES-256 키 갱신 주기와 매핑.
2. 고전 채널은 PQC 서명 또는 사전 공유 MAC으로 인증하고, key manager는 ITU-T Y.3803 구조에 맞춰 애플리케이션별 키 할당 정책 수립.
3. trusted node는 HSM, 출입통제, dual control, SIEM 감사로그를 적용하고 key starvation 0건 조건을 운영 SLO에 반영.

**결론 (2줄):**
- 기술사 판단: QKD는 범용 인터넷 대체가 아니라 전용 광 링크와 물리 보안 운영이 가능한 고가치 구간에 적용함.
- 향후 방향: 단기 전환은 PQC 중심, 초고가치 폐쇄망은 QKD+PQC 인증을 결합한 하이브리드 키 관리로 발전해야 함.
