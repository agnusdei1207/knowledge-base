## 미리 알고가기

- SOAR는 탐지를 대신하는 제품이 아니라 탐지 이후 조사와 조치를 자동화하는 운영 플랫폼임
- 플레이북과 승인 절차와 외부 시스템 연동이 핵심이며 SIEM과 자주 함께 동작함
- 잘못된 자동화는 오탐을 더 빠르게 확산시킬 수 있으므로 승인 정책이 중요함

## Ⅰ. 개요

- **정의/개념**: SOAR는 보안 경보와 사건 대응 절차를 플레이북으로 표준화하고 SIEM, EDR, 방화벽, 티켓 시스템과 연동해 조사와 조치와 보고를 자동화하는 보안 운영 플랫폼임
- **배경/필요성**: SOC는 같은 유형의 경보를 반복 처리하느라 분석가 피로와 대응 지연이 커지므로 반복 가능한 절차를 자동화해 속도와 일관성을 높일 필요가 있음

## Ⅱ. 특징

- 반복 대응 절차를 플레이북으로 만들어 같은 품질의 대응을 재현할 수 있음
- CTI 조회, 자산 조회, 티켓 생성, 계정 잠금, 단말 격리 같은 다중 작업을 오케스트레이션할 수 있음
- 승인 게이트를 넣어 자동 조치와 수동 검토를 업무 위험도에 맞게 조절할 수 있음
- 탐지 품질이 낮거나 연동 권한이 과도하면 오탐 자동 조치로 업무 중단을 유발할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 사고 대응 | SOAR |
|:---|:---|:---|
| 처리 방식 | 분석가가 개별 수행 | 플레이북 기반 자동 수행 |
| 속도와 일관성 | 담당자 역량에 좌우됨 | 표준 절차로 일정함 |
| 주요 강점 | 상황별 유연성 | 반복 업무와 대량 경보 처리 |
| 대표 한계 | 지연과 피로 누적 | 잘못된 자동화 위험 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Trigger | SIEM 경보나 티켓 생성처럼 플레이북을 시작시키는 사건 입력 계층임 |
| Playbook | 조회, 판단, 격리, 통보 순서를 정의한 자동화 절차 계층으로 운영 일관성의 중심임 |
| Integration Connectors | EDR, 방화벽, IAM, 메신저, CMDB와 연결해 실제 조치를 실행하는 연계 계층임 |
| Case Management | 증거와 진행 상태와 승인 이력을 관리하는 사건 관리 계층임 |
| Approval and Audit | 고위험 조치 승인과 실행 로그를 남겨 오동작과 감사 요구에 대응하는 통제 계층임 |

```text
+-----------+    +----------------+    +----------------+    +----------------+

+-----------+    +----------------+    +----------------+    +----------------+

                                                     v

                                               +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 경보 수신      | -> | 정보 보강      | -> | 조건 판단      | -> | 자동/승인 조치  | -> | 기록/종결      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **경보 수신**: SIEM이나 EDR이 경보를 전달함
2. **정보 보강**: CTI, 자산 정보, 사용자 정보로 문맥을 추가함
3. **조건 판단**: 위험 점수와 정책을 기준으로 처리 경로를 정함
4. **자동 또는 승인 조치**: 계정 잠금, IP 차단, 단말 격리, 티켓 생성 등을 수행함
5. **기록과 종결**: 조치 결과와 승인 이력을 남기고 사건을 닫음

## Ⅵ. 실무 적용 및 유의점

1. 대량 피싱 경보와 단순 IOC 차단은 SOAR 자동화 효과가 크지만 탐지 품질이 낮으면 정상 계정과 서비스까지 차단할 수 있으므로 위험도 기준과 승인 단계를 분리하고 플레이북 성공률과 오조치 건수와 평균 대응 시간을 확인함
2. SOC와 IR 팀은 조사 절차 표준화에 SOAR를 활용하기 좋지만 외부 시스템 권한이 과도하면 자동화가 새로운 관리 리스크가 되므로 최소 권한 API와 감사 로그를 적용하고 승인 우회 건수와 연동 실패율로 확인함

## Ⅶ. 결론

- SOAR의 핵심은 많은 일을 자동으로 하는 데 있지 않고 반복 대응을 표준화해 빠르고 일관되게 수행하되 오조치를 막는 승인 통제를 함께 두는 데 있음
