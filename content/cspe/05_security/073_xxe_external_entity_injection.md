## 미리 알고가기

- XXE는 XML 파서가 외부 엔티티를 해석하도록 두었을 때 서버 파일 읽기나 내부 요청이 발생하는 취약점임
- 핵심 원인은 XML 문서의 DTD와 외부 엔티티 기능을 불필요하게 허용하는 파서 설정에 있음
- XML 입력이 남아 있는 시스템은 애플리케이션 코드보다 파서 보안 설정부터 먼저 확인해야 함

## Ⅰ. 개요

- **정의/개념**: XXE는 공격자가 XML 문서의 외부 엔티티 정의를 이용해 서버가 로컬 파일이나 내부 네트워크 자원을 읽거나 요청하게 만드는 XML 파서 기반 취약점임
- **배경/필요성**: 레거시 연계, 문서 처리, SOAP 등에서 XML 사용이 남아 있고, 파서 기본 설정이 안전하지 않으면 파일 유출과 SSRF와 서비스 장애가 발생할 수 있어 주기적 통제가 필요함

## Ⅱ. 특징

- 취약점은 웹 화면보다 XML 파서 설정과 라이브러리 사용 방식에서 발생함
- 로컬 파일 읽기와 내부 URL 요청과 엔티티 확장 기반 DoS로 이어질 수 있음
- 입력값 검증만으로는 충분하지 않고 DTD와 외부 엔티티 기능 자체를 막아야 함
- JSON API로 전환해도 백엔드에서 XML 처리 모듈이 남아 있으면 위험이 지속될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 파일 읽기형 XXE | 요청 유도형 XXE |
|:---|:---|:---|
| 주요 목적 | 로컬 설정 파일과 비밀 정보 유출 | 내부 서비스 호출과 SSRF 유도 |
| 접근 대상 | `file://` 기반 로컬 자원 | `http://` 등 네트워크 자원 |
| 피해 형태 | 비밀번호, 키, 설정 정보 노출 | 내부 스캔, 메타데이터 접근, 연계 공격 |
| 공통 대응 | 외부 엔티티와 DTD 비활성화 | 외부 엔티티와 DTD 비활성화 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| XML 입력점 | 업로드 파일, SOAP 메시지, API 본문 등 XML이 들어오는 위치임 |
| DTD/외부 엔티티 | 외부 자원을 참조하게 만드는 선언 구문임 |
| XML 파서 | DOM, SAX, StAX 등 실제로 엔티티를 해석하는 라이브러리임 |
| 방어 통제 | DTD 비활성화, 안전한 파서 설정, 스키마 검증, 네트워크 제한이 포함됨 |

```text
악성 XML 입력 -> 외부 엔티티 해석 -> 파일/내부 자원 접근 -> 응답 또는 오류로 노출
```

## Ⅴ. 원리 및 절차 흐름도

```text
DTD 포함 XML 전송 -> 파서가 엔티티 해석 -> 서버 자원 접근 -> 응답/오류에 반영 -> 정보 노출
```

1. **악성 XML 전송**: 공격자가 외부 엔티티를 포함한 XML을 보냄
2. **파서 해석**: 서버가 DTD와 엔티티를 허용한 채 문서를 읽음
3. **자원 접근**: 로컬 파일이나 내부 URL을 읽거나 호출함
4. **결과 노출**: 응답 본문이나 오류 메시지에 내용이 포함될 수 있음
5. **후속 조치**: 파서 설정 수정과 영향 자산 점검을 수행함

## Ⅵ. 실무 적용 및 유의점

1. SOAP, SAML, 파일 업로드처럼 XML 처리가 남아 있는 시스템은 외부 엔티티와 DTD를 기본 비활성화하고 필요 기능만 허용해야 하며 대표 페이로드 재현 실패와 민감 파일 접근 로그 부재와 파서 설정 표준화 여부로 확인함
2. 레거시 제품 연동으로 XML을 유지해야 하는 환경은 애플리케이션 수정 외에 서버의 아웃바운드 통신과 파일 접근 권한도 제한해야 하며 내부 URL 접근 차단 여부와 예외 구성 정기 재검토 완료 여부로 확인함

## Ⅶ. 결론

- XXE는 입력 필드의 문제가 아니라 XML 파서가 불필요한 외부 참조를 신뢰하는 구조적 문제이므로 파서 설정과 네트워크 권한을 함께 줄여야 함
