## Ⅰ. 개요
- **정의**: XML 파서가 외부 엔티티를 처리하도록 유도하여 서버 파일 읽기, SSRF 등을 수행하는 공격
- **배경/필요성**: XML 파서가 DTD 외부 엔티티를 기본 허용하면 서버 내부 리소스가 공격자에게 노출됨
- **비유**: 도서관 사서에게 외부 창고의 비밀 문서를 가져오라고 속이는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| XML 기반 취약점 이해 | DTD 외부 엔티티 처리가 근본 원인 | SSRF와의 연계 공격 패턴 언급 |

> 요약: XXE는 XML 파서의 외부 엔티티 해석 기능을 악용하여 서버 자원에 무단 접근하는 공격임

## Ⅱ. 구성요소
```text
공격자 --악성XML--> XML 파서 --엔티티 요청--> 내부파일/외부URL
                       |
                       v
                  응답에 파일 내용 포함
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DTD 선언 | `<!DOCTYPE>` 내 외부 엔티티(`SYSTEM`)를 정의하는 구문 | 외부 참조 지시서 |
| XML 파서 | SAX, DOM 등 XML을 해석하는 라이브러리 | 지시를 따르는 사서 |
| 외부 엔티티 | `file://`, `http://` 등 URI로 지정된 외부 리소스 | 외부 창고 문서 |

> 요약: DTD의 외부 엔티티 선언을 XML 파서가 무조건 처리하는 것이 공격의 핵심임

## Ⅲ. 절차
```text
악성 DTD 작성 --> XML 전송 --> 파서가 엔티티 해석 --> 내부 자원 유출
```
- 1단계: 악성 DTD 작성 — `<!ENTITY xxe SYSTEM "file:///etc/passwd">` 형태로 외부 엔티티를 정의함
- 2단계: XML 전송 — API 요청 본문이나 파일 업로드를 통해 악성 XML을 서버에 전달함
- 3단계: 파서 해석 — 서버의 XML 파서가 DTD를 처리하며 지정 URI의 리소스를 읽어옴
- 4단계: 자원 유출 — 읽어온 파일 내용이 XML 응답이나 에러 메시지에 포함되어 노출됨

> 요약: 악성 DTD 정의-전송-파서 해석-자원 유출의 4단계로 서버 내부 파일이 노출됨

## Ⅳ. 문제점
- 파일 노출: `/etc/passwd`, 설정 파일 등 서버 내부 파일이 공격자에게 유출됨
- SSRF 연계: 외부 엔티티 URI를 내부 네트워크 주소로 설정하여 내부 서비스에 접근함
- DoS 가능: 재귀 엔티티 참조(Billion Laughs)로 메모리를 고갈시킬 수 있음

> 요약: 파일 노출, SSRF 연계, DoS가 XXE의 주요 피해 유형임

## Ⅴ. 개선방안
1. 단기: XML 파서에서 외부 엔티티 처리를 비활성화함(`disallow-doctype-decl`)
2. 중기: XML 대신 JSON 기반 API로 전환하여 DTD 공격 표면을 제거함
3. 장기: 입력 XML 스키마 검증과 WAF XML 페이로드 검사 규칙을 표준화함

> 요약: 외부 엔티티 비활성화, JSON 전환, 스키마 검증으로 XXE를 근본 차단함

## Ⅵ. 전망
- 발전 방향: REST/JSON 전환으로 XXE 발생 빈도는 감소하나 레거시 SOAP/XML 시스템에서 여전히 유효함
- 기술사적 판단: OWASP Top 10에 지속 등재되어 XML 사용 시스템의 보안 점검 항목으로 유지될 전망
- 기술사 제언: XML을 사용하는 레거시 API에 대해 파서 설정 감사와 외부 엔티티 비활성화 점검이 필요함
