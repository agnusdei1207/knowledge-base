## 미리 알고가기

- 프라이버시 기본값은 사용자가 별도 조작하지 않아도 최소 수집과 최소 공개가 기본으로 적용되는 상태임
- 데이터 최소화는 목적 달성에 필요한 범위만 수집하고 오래 보관하지 않는 설계 원칙임
- 설계 검토 게이트는 기능 출시 전에 법적·기술적 요구를 확인하는 내부 승인 단계임

## Ⅰ. 개요

- **정의/개념**: 프라이버시 중심 설계는 개인정보 보호 기능을 서비스 출시 뒤 덧붙이지 않고 요구사항 정의와 화면 설계와 데이터 구조 단계부터 기본 설계에 넣는 접근 방식임
- **배경/필요성**: 서비스가 열린 뒤에 동의 화면이나 삭제 기능이나 접근 통제를 뒤늦게 붙이면 비용이 크고 누락도 많아지므로, 초기 구조에서부터 개인정보 처리 방식을 바로 잡을 필요가 있음

## Ⅱ. 특징

- 사고가 난 뒤 수습하는 방식보다 사전 예방에 무게를 둠
- 최소 수집과 기본 비공개 설정을 시스템 기본값으로 둠
- 기능 개발, 운영 정책, 사용자 권리 처리 절차를 한 구조 안에서 다룸
- 설계 단계에서 반영할수록 재작업과 규제 대응 비용을 줄이기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 프라이버시 중심 설계 | 출시 후 보완 방식 |
|:---|:---|:---|
| 반영 시점 | 요구사항과 설계 단계에서 반영함 | 사고나 민원 뒤에 기능을 붙임 |
| 수집 구조 | 처음부터 최소 수집을 기준으로 잡음 | 이미 쌓인 데이터를 줄이기 어려움 |
| 사용자 경험 | 동의, 철회, 삭제가 자연스럽게 연결됨 | 별도 메뉴와 우회 절차가 생기기 쉬움 |
| 운영 비용 | 초기 검토 부담은 있지만 재작업이 줄어듦 | 늦게 고칠수록 수정 범위와 비용이 커짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 요구사항 검토 | 처리 목적과 법적 근거와 필요한 데이터 범위를 초기에 정리하는 단계임 |
| 데이터 최소화 설계 | 필수 항목과 선택 항목을 나누고 불필요한 수집을 막는 구조 설계임 |
| 기본 설정 정책 | 공개 범위, 마케팅 동의, 보유 기간 같은 값을 보호 중심 기본값으로 두는 장치임 |
| 권리 처리 인터페이스 | 열람, 정정, 삭제, 철회 요청을 사용자가 쉽게 수행하게 하는 기능 계층임 |
| 검토와 감사 | 출시 전 설계 검토와 출시 후 점검을 이어 주는 운영 통제임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 요구사항 정의  | -> | 최소 수집 설계 | -> | 기본값 설정    | -> | 권리 처리 구현 |
+-------------+    +-------------+    +-------------+    +-------------+
       |
       v
+-------------+
| 검토와 감사  |
+-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 목적 정리      | -> | 수집 항목 선정  | -> | 기본값 설정    | -> | 기능 구현      | -> | 출시 전 검토   |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **목적 정리**: 어떤 서비스를 위해 어떤 개인정보가 필요한지 먼저 정함
2. **수집 항목 선정**: 꼭 필요한 항목만 남기고 불필요한 필드는 제거함
3. **기본값 설정**: 공개 범위와 마케팅 수신 같은 옵션을 보호 중심으로 기본 설정함
4. **기능 구현**: 권리 행사, 로그, 삭제, 보관 기간 자동화 기능을 함께 구현함
5. **출시 전 검토**: 설계 검토 게이트에서 실제 구현이 원칙과 맞는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 신규 앱은 화면 설계 단계에서 미사용 수집 항목을 먼저 없애고 선택 동의 기본값과 삭제 기능 동작을 검토하며 미사용 필드 수와 철회 처리 완료 시간을 핵심 지표로 봄
2. 추천 기능이나 AI 기능을 추가할 때는 설계 검토 게이트에서 목적 외 재사용 여부를 확인하고 출시 직전 재작업 건수와 검토 누락 기능 수로 통제 수준을 확인함

## Ⅶ. 결론

프라이버시 중심 설계는 보호 기능을 나중에 붙이는 일이 아니라 서비스 구조 자체를 바꾸는 일이므로 요구사항 단계부터 반영해야 효과가 남음.
