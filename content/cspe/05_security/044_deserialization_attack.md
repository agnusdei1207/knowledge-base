## Ⅰ. 개요
- **정의**: 신뢰할 수 없는 직렬화 데이터를 역직렬화하여 원격 코드 실행을 유발하는 공격
- **배경/필요성**: 객체 전송에 직렬화를 사용하는 시스템이 많아 공격 표면이 광범위함
- **비유**: 택배 상자를 열면 자동으로 작동하는 장치가 내장된 것과 유사

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 역직렬화 취약점 원리와 방어 | 가젯 체인·RCE 연결 경로 | 언어별 차이(Java·Python·PHP) 언급 필요 |

> 요약: 직렬화 객체에 악성 페이로드를 삽입하여 서버에서 임의 코드를 실행하는 공격임

## Ⅱ. 구성요소
```text
Attacker -> Malicious Payload -> Deserializer -> Gadget Chain -> RCE
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 악성 직렬화 페이로드 | 조작된 객체 바이트스트림 | 위조된 택배 상자 |
| 역직렬화 엔진 | 바이트스트림을 객체로 복원하는 런타임 함수 | 상자 자동 개봉기 |
| 가젯 체인 | 기존 클래스의 메서드를 연쇄 호출하여 RCE에 도달하는 경로 | 도미노 연쇄 반응 |

> 요약: 페이로드-역직렬화 엔진-가젯 체인이 결합하여 원격 실행에 도달함

## Ⅲ. 절차
```text
페이로드 생성 -> 전송 -> 역직렬화 실행 -> 코드 실행
```
- 1단계: 공격자가 가젯 체인을 포함한 직렬화 페이로드 생성
- 2단계: HTTP 요청·메시지 큐 등을 통해 대상 서버로 페이로드 전송
- 3단계: 서버의 역직렬화 함수가 페이로드를 객체로 복원하며 가젯 체인 실행
- 4단계: 가젯 체인이 시스템 명령 실행·파일 쓰기 등 RCE 수행

> 요약: 조작된 객체가 복원되는 시점에 가젯 체인이 연쇄 실행되어 RCE에 도달함

## Ⅳ. 문제점
- 무검증 역직렬화: 입력 데이터의 타입·출처 검증 없음 — 임의 객체 복원 가능
- 과다 클래스 로딩: 불필요한 라이브러리가 클래스패스에 포함 — 가젯 체인 소재 제공
- 탐지 어려움: 정상 직렬화 트래픽과 구분 불가 — 시그니처 기반 탐지 회피 가능

> 요약: 무검증·과다 라이브러리·탐지 한계가 공격 성공률을 높임

## Ⅴ. 개선방안
1. 단기: 역직렬화 입력에 타입 화이트리스트 적용(예: `ObjectInputFilter`)
2. 중기: 불필요한 라이브러리를 클래스패스에서 제거하여 가젯 체인 소재 차단
3. 장기: JSON 등 데이터 전용 포맷으로 전환하여 객체 역직렬화 자체를 제거

> 요약: 화이트리스트·의존성 정리·포맷 전환으로 공격 경로를 근본 차단함

## Ⅵ. 전망
- 발전 방향: 언어 런타임 수준에서 안전한 역직렬화 메커니즘이 기본 탑재될 것임
- 기술사적 판단: OWASP A08 항목으로 지속 관리가 필요한 위협임
- 기술사 제언: 신규 시스템 설계 시 객체 직렬화 대신 데이터 전용 포맷 채택을 제언함
