## 미리 알고가기

- 보안 구성 관리는 서버와 네트워크와 클라우드와 애플리케이션의 설정값을 보안 기준선에 맞게 유지하는 활동임
- 취약점이 없어도 과다 공개 포트, 기본 계정, 약한 암호 설정, 공개 스토리지는 침해 경로가 될 수 있음
- 핵심은 초기 하드닝보다 운영 중 변경으로 생기는 구성 편차를 계속 줄이는 데 있음

## Ⅰ. 개요

- **정의/개념**: 보안 구성 관리는 시스템과 서비스 설정을 기준선과 비교해 오설정과 구성 편차를 탐지·시정하는 운영 통제임
- **배경/필요성**: 클라우드와 자동 배포로 설정 변경이 잦아짐. 오설정은 취약점보다 빠르게 공격 표면을 넓힐 수 있음

## Ⅱ. 특징

- 보안 기준선과 실제 운영 상태를 지속 비교해 편차를 확인함
- 서버, 클라우드 보안 그룹, IAM, 컨테이너, 보안 헤더까지 포함함
- 수동 점검만으로는 규모를 감당하기 어려워 IaC와 정책 자동화가 필요함
- 예외 승인과 만료일 관리가 없으면 임시 변경이 상시 설정으로 굳어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 점검 중심 관리 | 지속적 보안 구성 관리 |
|:---|:---|:---|
| 점검 시점 | 정기 감사 시 일회성 확인 | 배포 전후와 운영 중 상시 확인 |
| 적용 범위 | 일부 서버와 장비 위주 | 서버, 클라우드, 컨테이너, 애플리케이션 전반 |
| 장점 | 시작이 단순함 | 편차 탐지와 자동 시정이 가능함 |
| 한계 | 누락과 지연이 많음 | 기준선 설계와 자동화 체계가 필요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 보안 기준선 | OS, DB, 클라우드, 쿠버네티스, 애플리케이션 설정 기준을 정의함 |
| 자산 및 상태 수집 | 실제 설정값과 정책과 배포 상태를 수집함 |
| 편차 탐지 | 기준선과 운영 상태를 비교해 위반 항목을 찾음 |
| 시정 및 예외 관리 | 자동 수정, 수동 조치, 예외 승인과 만료일을 관리함 |

```text
기준선 정의 -> 자산 상태 수집 -> 편차 탐지 -> 시정/예외 승인 -> 재확인
```

## Ⅴ. 원리 및 절차 흐름도

```text
하드닝 기준 수립 -> 배포 전 정책 검사 -> 운영 중 드리프트 탐지 -> 시정 조치 -> 감사 증적 보관
```

1. **기준 수립**: 조직 보안 정책과 표준을 바탕으로 설정 기준을 만듦
2. **배포 전 검사**: IaC와 이미지와 설정 파일이 기준을 충족하는지 확인함
3. **운영 중 탐지**: 실제 자산 상태를 수집해 편차를 찾음
4. **시정 조치**: 자동 수정이나 변경 요청으로 설정을 바로잡음
5. **감사 증적 관리**: 위반 이력과 예외 승인 근거를 남김

## Ⅵ. 실무 적용 및 유의점

1. 클라우드·컨테이너 환경은 보안 그룹, IAM, 이미지 설정을 코드화하고 정책 위반 배포 차단율·드리프트 감소율로 확인함
2. 레거시 서버는 고위험 설정부터 기준선을 정하고 기본 계정 제거 여부·불필요 포트 축소·재점검 해소율로 확인함

## Ⅶ. 결론

- 보안 구성 관리는 기준선과 실제 상태의 차이를 계속 줄여 공격 표면을 통제하는 운영 체계임
