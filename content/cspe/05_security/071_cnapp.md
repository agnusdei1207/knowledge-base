## Ⅰ. 개요
- **정의**: 클라우드 네이티브 앱의 개발-배포-운영 전 주기를 통합 보호하는 플랫폼
- **배경/필요성**: CSPM, CWPP, CIEM 등 개별 보안 도구가 난립하면서 컨텍스트 단절과 알림 피로가 발생하여 통합 플랫폼이 필요함
- **비유**: 여러 전문의를 한 병원에 모아 놓은 종합병원과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 보안 통합 이해 | CSPM+CWPP+CIEM 통합 | 단순 나열이 아닌 통합 파이프라인 관점 서술 |

> 요약: CNAPP는 분산된 클라우드 보안 기능을 단일 플랫폼으로 통합하여 컨텍스트 기반 위협 대응을 수행함

## Ⅱ. 구성요소
```text
+----------+     +----------+     +----------+
|  CSPM    | --> |  CWPP    | --> |  CIEM    |
+----------+     +----------+     +----------+
      |                |                |
      v                v                v
+--------------------------------------------+
|        통합 위험 상관분석 엔진              |
+--------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CSPM | 클라우드 설정 오류 탐지 및 컴플라이언스 점검 | 건물 안전 점검관 |
| CWPP | 워크로드(VM, 컨테이너, 서버리스) 런타임 보호 | 경비원 |
| CIEM | 클라우드 IAM 권한 과다 부여 탐지 및 최소 권한 적용 | 출입증 관리자 |
| IaC 스캔 | Terraform, CloudFormation 등 코드 단계 취약점 사전 탐지 | 설계도 검수자 |

> 요약: CSPM, CWPP, CIEM, IaC 스캔이 통합 엔진에서 상관분석되어 위험 우선순위를 산출함

## Ⅲ. 절차
```text
IaC 코드 스캔 --> 배포 시 이미지 검증 --> 런타임 워크로드 모니터링 --> 위험 상관분석/대응
```
- 1단계: IaC 코드 스캔 — 배포 전 설정 오류와 취약점을 코드 레벨에서 탐지함
- 2단계: 이미지 검증 — 컨테이너 이미지의 CVE, 서명 무결성을 빌드 파이프라인에서 검사함
- 3단계: 런타임 모니터링 — 워크로드 행위, 네트워크 흐름, 권한 사용을 실시간 감시함
- 4단계: 상관분석/대응 — 다중 소스 이벤트를 결합하여 공격 경로를 식별하고 자동 격리함

> 요약: 코드-빌드-런타임-대응의 4단계 파이프라인으로 클라우드 앱 전 주기를 보호함

## Ⅳ. 문제점
- 벤더 종속: 단일 플랫폼 의존 시 멀티클라우드 환경에서 특정 CSP 기능 누락 발생
- 알림 과다: 통합으로 수집 데이터가 증가하여 상관분석 튜닝 없이는 알림 피로 지속
- 레거시 호환: 온프레미스 워크로드나 VM 기반 시스템에 에이전트 배포가 곤란함

> 요약: 벤더 종속, 알림 과다, 레거시 호환 문제가 CNAPP 도입의 주요 장애물임

## Ⅴ. 개선방안
1. 단기: 멀티클라우드 API 추상화 계층을 도입하여 CSP별 차이를 표준화함
2. 중기: 위험 점수 기반 우선순위 필터링과 자동 튜닝 규칙을 적용하여 알림을 정제함
3. 장기: 에이전트리스 스캔과 eBPF 기반 경량 센서를 병행하여 레거시 환경을 포괄함

> 요약: API 추상화, 알림 튜닝, 에이전트리스 확장으로 CNAPP 실효성을 확보함

## Ⅵ. 전망
- 발전 방향: ASPM(Application Security Posture Management)과 결합하여 코드-클라우드 전 구간 통합 보안으로 확장
- 기술사적 판단: 클라우드 네이티브 전환이 가속되면서 CNAPP는 보안 플랫폼의 표준 형태가 될 것임
- 기술사 제언: 조직의 클라우드 성숙도에 맞춰 CSPM 우선 도입 후 단계적으로 CWPP, CIEM을 통합하는 로드맵 수립이 필요함
