## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 한 번의 인증으로 연계된 다수의 시스템·서비스에 추가 로그인 없이 접근할 수 있는 통합 인증 체계임 |
| **배경/필요성** | 서비스 증가에 따른 반복 로그인으로 사용자 피로·패스워드 메모 관행이 발생하며, 중앙 인증 관리가 필요함 |
| **출제 의도** | SSO 구현 방식(에이전트·토큰·SAML·OIDC)과 보안 고려사항을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 인증서버  | --> | 세션토큰  | --> | 연계서비스|
| (IdP)    |     | (Session)|     | (SP 1~N) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 인증 서버(IdP) | 중앙에서 사용자 인증을 수행하고 세션·토큰을 발급함 | 놀이공원 통합 매표소 |
| 세션 토큰 | 인증 완료를 증명하는 쿠키·JWT로 각 서비스에 인증 상태를 전달함 | 자유이용권 팔찌 |
| 연계 서비스(SP) | 세션 토큰을 검증하여 추가 로그인 없이 접근을 허용하는 개별 서비스임 | 놀이공원 개별 놀이기구 |

> 요약: 중앙 인증 서버가 발급한 세션 토큰으로 연계 서비스에 재인증 없이 접근하는 체계임.

## Ⅲ. 절차
```
+------------+     +------------+
| 서비스접근  | --> | IdP인증   |
| (미인증)   |     | (1회로그인)|
+------------+     +------------+
                        |
+------------+     +----+-------+
| 타서비스   | <-- | 세션토큰  |
| 자동접근   |     | 발급·전달  |
+------------+     +------------+
```

1. 서비스 접근: 사용자가 서비스 A에 접근하나 인증 세션이 없음
2. IdP 인증: IdP 로그인 화면에서 1회 인증(ID/PW + MFA)을 수행함
3. 세션 토큰 발급: IdP가 세션 쿠키·SAML Assertion·OIDC ID Token을 발급함
4. 타 서비스 자동 접근: 서비스 B·C 접근 시 IdP 세션이 유효하므로 추가 로그인 없이 토큰이 자동 발급됨

> 요약: 1회 인증 → 세션 토큰 발급 → 연계 서비스 자동 접근으로 SSO가 구현됨.

## Ⅳ. 문제점
- 단일 장애점: IdP 장애 시 전체 연계 서비스 접근이 불가함
- 세션 탈취 파급: SSO 세션 쿠키가 탈취되면 모든 연계 서비스에 무단 접근이 가능함
- 로그아웃 불완전: SLO(Single Logout) 구현 시 모든 SP의 세션을 완전히 종료하기 어려움

## Ⅴ. 개선방안
- (단기) IdP HA 구성: Active-Active 이중화로 단일 장애점을 제거함
- (중기) 세션 보호 강화: 세션 쿠키에 HttpOnly·Secure·SameSite 속성을 적용하고 짧은 만료를 설정함
- (장기) 연속 인증 연동: SSO 세션 중에도 고위험 행위 시 Step-up 인증을 요구하여 세션 탈취 피해를 제한함

## Ⅵ. 전망
- OIDC 기반 SSO가 클라우드 서비스의 표준이 되며, FIDO2 패스키와 결합한 패스워드리스 SSO가 엔터프라이즈 인증의 최종 형태로 자리잡을 전망임
