## 미리 알고가기

- SSO는 한 번 로그인으로 여러 서비스에 다시 비밀번호를 넣지 않고 접근하게 하는 방식임
- SAML이나 OIDC는 SSO를 구현하는 기술이고, SSO 자체는 사용자 경험과 중앙 인증 구조를 가리키는 개념임
- 편리하지만 중앙 인증 세션이 흔들리면 여러 서비스가 함께 영향을 받는다는 점도 봐야 함

## Ⅰ. 개요

- **정의/개념**: SSO는 중앙 인증 체계에서 한 번 신원을 확인하면 여러 서비스가 그 결과를 신뢰해 추가 로그인 없이 접근을 허용하는 방식임
- **배경/필요성**: 서비스가 늘수록 비밀번호 재사용과 계정 정책 편차가 커짐. 중앙 인증과 재사용 가능한 로그인 체계가 필요함

## Ⅱ. 특징

- 사용자 경험을 개선하고 비밀번호 재입력 횟수를 줄임
- 인증 정책과 MFA를 중앙에서 일관되게 적용하기 쉬움
- 중앙 인증 장애가 전체 서비스 접근성에 영향을 줄 수 있음
- 고위험 행위에는 추가 인증을 다시 요구하는 설계가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 개별 로그인 | SSO |
|:---|:---|:---|
| 로그인 횟수 | 서비스마다 별도 인증 | 중앙 1회 인증 후 재사용 |
| 정책 적용 | 서비스별 편차가 큼 | 인증 정책 중앙 통제가 쉬움 |
| 장애 영향 | 개별 서비스 단위 | 중앙 IdP 장애 시 파급이 큼 |
| 사용자 위험 | 비밀번호 재사용 유도 | 세션 탈취 시 영향 범위가 넓음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Identity Provider | 중앙 인증과 세션 발급을 담당함 |
| Federation Protocol | SAML, OIDC 등 서비스 간 인증 결과 전달 방식을 담당함 |
| Service Providers | 중앙 인증 결과를 받아 각 서비스 세션을 만듦 |
| Session and Logout | 로그인 유지와 로그아웃 전파를 관리함 |

```text
중앙 인증 -> 신뢰 토큰 전달 -> 각 서비스 세션 생성 -> 필요 시 추가 인증 -> 로그아웃 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 접근 -> IdP 인증 -> 토큰/Assertion 발급 -> 연계 서비스 검증 -> 세션 재사용
```

1. **서비스 접근**: 사용자가 한 서비스에 접속함
2. **IdP 인증**: 중앙 인증 서버가 로그인과 MFA를 처리함
3. **토큰 전달**: 인증 결과가 SAML 또는 OIDC 형태로 서비스에 전달됨
4. **세션 생성**: 서비스가 결과를 검증하고 자체 세션을 발급함
5. **다른 서비스 재사용**: 같은 IdP 세션을 바탕으로 추가 로그인이 생략됨

## Ⅵ. 실무 적용 및 유의점

1. 사내 포털·SaaS 환경은 IdP 이중화와 비상 로그인 경로를 함께 설계하고 인증 가용성·중앙 세션 장애 복구 시간으로 확인함
2. 중요 기능은 추가 인증을 넣고 관리자 기능 추가 인증 적용률·세션 탈취 시나리오 차단 여부로 확인함

## Ⅶ. 결론

- SSO는 로그인 횟수 감소 기능이 아니라 중앙 인증 신뢰를 여러 서비스로 안전하게 재사용하도록 설계하는 체계임
