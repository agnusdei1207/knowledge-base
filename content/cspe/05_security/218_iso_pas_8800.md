# 📖 【암기용】 개념 완전 이해

> 목적: ISO/PAS 8800을 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 양산 도로차량의 AI 포함 safety-related E/E systems에 적용하는 자동차 AI 안전 지침
- **왜 필요한가**: AI 모델은 규칙 코드와 달리 데이터, ODD, 학습 편향, 미지 상황에서 동작이 달라질 수 있다. 자율주행·ADAS가 판단 오류를 내면 안전 기능에 직접 영향이 생긴다.
- **핵심 직관**: ISO/PAS 8800은 AI가 운전 판단에 들어갈 때 "학습 데이터와 운영 조건까지 안전 요구사항으로 관리하라"는 기준이다.

## 깊이 이해
- **배경·문제의식**: ISO 26262는 하드웨어·소프트웨어 고장에 대한 기능 안전을 다루고, ISO 21448(SOTIF)은 의도 기능의 한계와 오용을 다룬다. AI는 데이터셋 품질, 학습·검증 분포, 설명 가능성, 런타임 모니터링이 추가로 필요해 별도 지침이 요구됨.
- **작동 원리**: ISO/PAS 8800:2024는 Road vehicles - Safety and artificial intelligence로 양산 도로차량의 AI 포함 safety-related E/E systems에 적용된다. AI safety lifecycle에서 데이터 요구사항, 모델 검증, ODD, 모니터링, fail-safe를 안전 케이스로 연결한다.
- **비유**: 운전 보조 AI는 신입 운전자와 같다. 면허 시험뿐 아니라 어떤 도로·날씨·표지판에서 운전 가능한지, 실수하면 누가 제동하는지까지 정해야 한다.
- **구체 예시**: 보행자 인식 AI가 야간·우천 ODD에서 재현율 90% 미만이면 시스템은 경고·감속·운전자 인계 조건을 둔다. 데이터셋에는 낮/밤, 비/눈, 역광, 가림 상황 비율을 기록함.
- **흔한 오해·주의점**: ISO/PAS 8800은 AI 성능 순위표가 아니다. ISO 26262, ISO 21448, ISO/SAE 21434와 함께 안전·기능 한계·보안을 통합하는 안전 논증 체계이다.

## 연결 개념
- ISO 26262 - 전기전자 시스템 기능 안전
- ISO 21448 SOTIF - 의도 기능 안전과 ODD 한계
- ISO/SAE 21434 - 차량 사이버보안 수명주기

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 수치·표준·도식·문제유형 전환을 엄격히 적용한다.
> 핵심: ISO/PAS 8800은 AI 모델 자체가 아니라 데이터·ODD·검증·모니터링·fail-safe를 안전 케이스로 묶는 차량 AI 안전 지침이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO/PAS 8800:2024는 양산 도로차량의 AI 포함 safety-related E/E systems에 적용하는 Road vehicles - Safety and artificial intelligence 지침이다.
> 2. **가치**: AI 데이터셋, ODD, 모델 검증, 런타임 모니터링, fail-safe를 안전 요구사항으로 추적해 ADAS·자율주행 오동작 위험을 낮춘다.
> 3. **판단 포인트**: ISO 26262는 고장, ISO 21448은 기능 한계, ISO/SAE 21434는 사이버 위협, ISO/PAS 8800은 AI 안전 위험을 담당한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 자동차 AI 안전 표준 관계 확인 | ISO/PAS 8800:2024, ISO 26262, ISO 21448, ISO/SAE 21434 | AI 윤리 일반론으로 답안 전개 |
| AI safety lifecycle 이해 확인 | dataset, ODD, validation, monitoring, fail-safe | 모델 정확도만 쓰고 ODD·운영 감시 누락 |
| 양산 시스템 적용 판단 확인 | safety-related E/E systems, safety case, 변경관리 | 연구용 AI 평가와 양산 안전 인증 혼동 |

> 요약: 이 문제는 차량 AI를 데이터와 운영 조건까지 포함한 안전 요구사항으로 관리하는 능력을 평가한다.

## Ⅰ. 개요 및 필요성

- 개요: 차량 AI 안전 요구사항 지침
- 배경: AI 기반 ADAS·자율주행은 학습 데이터 분포, ODD 이탈, 미지 시나리오에서 예측 오류가 발생할 수 있음
- 필요성: ISO/PAS 8800:2024를 ISO 26262·ISO 21448·ISO/SAE 21434와 연계해 데이터셋, ODD, validation, runtime monitoring, fail-safe를 안전 케이스로 추적해야 함

---

## Ⅱ. 구조 및 구성요소

```text
AI Safety Requirement -> Dataset -> Model Training/Validation
-> ODD Definition -> Runtime Monitoring -> Fail-safe/MRM
Relation -> ISO 26262 / ISO 21448 / ISO 21434 -> Safety Case
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Dataset 요구사항 | 학습·검증 데이터 분포와 라벨 품질 관리 | 낮/밤·날씨·가림·지역 편향 기록 |
| ODD | 운행 가능한 도로·환경·속도 조건 한정 | ODD 이탈 시 경고·인계 필요 |
| Validation | 모델 요구사항 충족 검증 | 재현율, 오탐률, 시나리오 커버리지 |
| Monitoring/Fail-safe | 런타임 이상 감시와 안전 상태 전환 | MRM, fallback, 운전자 인계 |

> 요약: ISO/PAS 8800 구조는 데이터-모델-ODD-감시-fail-safe를 안전 케이스로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Hazard 식별 -> AI 안전 요구사항 수립 -> Dataset 기준 설정
-> 모델 학습·검증 -> ODD 적합성 확인 -> 운영 감시
-> Fail-safe 전환 -> 안전 케이스 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 기능과 안전 관련 시나리오 식별 | ASIL/SOTIF 연계 항목 식별 |
| 2 | Dataset 요구사항과 라벨 품질 기준 수립 | 라벨 오류율 1% 이하 |
| 3 | ODD별 모델 검증과 시나리오 테스트 수행 | ODD 커버리지 95% 이상 |
| 4 | 런타임 모니터링·confidence threshold 설정 | 오동작 감지 시간 1초 이내 |
| 5 | Fail-safe, MRM, 운전자 인계 검증 | fallback 성공률 99% 이상 |

> 요약: AI 안전은 학습 전 데이터 기준부터 양산 후 모니터링까지 추적성을 유지해야 한다.

## Ⅳ. 특징

| 구분 | 기존 차량 안전 | ISO/PAS 8800 AI 안전 | 수치·표준 포인트 |

| 대상 위험 | 고장, 결함, 요구사항 누락 | 데이터 편향, ODD 이탈, 모델 불확실성 | ISO/PAS 8800:2024 |
| 검증 단위 | 코드·부품·시스템 테스트 | 데이터셋·시나리오·모델·런타임 | 커버리지 95% 이상 |

> 요약: ISO/PAS 8800은 AI 모델을 차량 안전 수명주기 안으로 편입해 데이터와 운영 조건까지 관리한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | ISO/PAS 8800 AI 안전 | 선택 기준 |
|:---|:---|:---|:---|
| 기능 안전 | ISO 26262 | AI 데이터·모델 안전 요구사항 추가 | AI가 안전 관련 판단에 관여 시 |
| 기능 한계 | ISO 21448 SOTIF | ODD·미지 상황·불확실성 관리 강화 | 고장 없는 오인식 위험 존재 시 |
| 보안 | ISO/SAE 21434 | 데이터·모델 변조와 안전 영향 연결 | AI 파이프라인 공격 가능 시 |

> 요약: ISO/PAS 8800은 기존 안전·보안 표준을 대체하지 않고 AI 특화 위험을 보완한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 데이터 편향 | 특정 날씨·지역·객체 부족 | 데이터 균형, 라벨 감사, 합성 데이터 검증 | 시나리오별 샘플 비율 |
| ODD 이탈 | 미지원 환경에서 기능 지속 | ODD 감지, 경고, MRM 전환 | ODD 이탈 감지율 99% |
| 모델 변조 | 학습 데이터·모델 파일 공격 | 서명, SBOM, 접근통제, 재현 학습 | 모델 해시 검증 100% |

> 요약: AI 안전 리스크는 편향·ODD 이탈·변조로 나뉘며 데이터 거버넌스와 런타임 전환으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 품질 | 라벨 오류율 1% 이하, 누락 시나리오 0건 | 샘플링 감사, 데이터 리포트 |
| 모델 안전 | 재현율·오탐률 ODD별 목표 충족 | SIL/HIL, 주행 시나리오 테스트 |
| 운영 감시 | 오동작 탐지 1초 이내, OTA 변경 승인 100% | 차량 로그, 모니터링 대시보드 |

> 요약: 적용 여부는 모델 점수보다 데이터 품질, ODD별 검증, 운영 감시 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 안전 요구사항을 ISO 26262 HARA, ISO 21448 시나리오, ISO/PAS 8800 dataset 요구사항으로 100% 추적
2. ODD별 데이터셋 분포표와 라벨 감사 절차를 만들고, 라벨 오류율 1% 이하·시나리오 커버리지 95% 이상 기준 적용
3. 런타임 confidence monitoring, ODD 이탈 감지, MRM 전환을 차량 로그와 OTA 변경관리로 운영

**결론 (2줄):**
- 기술사 판단: AI가 제동·조향·인지 판단에 관여하면 ISO/PAS 8800을 ISO 26262·SOTIF·21434와 통합 적용함
- 향후 방향: SDV와 생성형 AI 기반 차량 기능 확대로 데이터 계보, 모델 변경 승인, 운영 모니터링이 안전 인증의 주요 증적이 됨
