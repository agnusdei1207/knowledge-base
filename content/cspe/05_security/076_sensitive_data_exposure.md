## 미리 알고가기

- 민감 데이터는 개인정보, 인증 정보, 결제 정보, 영업 비밀처럼 유출 시 피해가 큰 데이터를 뜻함
- 데이터는 저장 중뿐 아니라 전송 중, 처리 중, 로그와 백업과 캐시에 복제된 상태에서도 노출될 수 있음
- 키 관리 시스템(KMS)은 암호키 생성과 저장과 회전을 중앙에서 관리하는 체계임
- HTTPS 적용만으로 충분하지 않고 데이터 최소 수집과 마스킹과 키 관리가 함께 있어야 함

## Ⅰ. 개요

- **정의/개념**: 민감 데이터 노출은 중요한 정보가 암호화, 마스킹, 접근 통제 없이 저장·전송·표시되어 외부에 드러나는 문제임
- **배경/필요성**: API 응답, 로그, 백업, 객체 스토리지, 관리자 화면에서 데이터가 새어 나갈 수 있음. 생명주기 전체 보호가 필요함

## Ⅱ. 특징

- 데이터베이스뿐 아니라 로그, 캐시, 파일 저장소, 화면 출력까지 점검함
- 암호화만으로는 부족하며 과다 수집과 과다 노출을 줄여야 함
- 저장 위치와 사용 목적에 따라 마스킹과 접근 권한 기준이 달라짐
- 개인정보보호, 결제 보안, 감사 대응이 함께 얽혀 운영 협업이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 저장 데이터 노출 | 전송·응답 데이터 노출 |
|:---|:---|:---|
| 주된 위치 | DB, 백업, 파일, 객체 스토리지 | API 응답, 브라우저, 내부 연계, 로그 |
| 대표 원인 | 평문 저장, 공개 버킷, 약한 접근 통제 | 과다 응답, 평문 전송, 마스킹 누락 |
| 피해 형태 | 대량 유출과 장기 보관 데이터 노출 | 세션 탈취, 즉시 재사용, 화면 캡처 노출 |
| 기본 대응 | 저장 암호화, 권한 분리, 보존 정책 | TLS, 응답 최소화, 마스킹, 토큰 축소 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 분류 | 어떤 데이터를 민감 정보로 볼지 기준을 정함 |
| 보호 통제 | 저장 암호화, 전송 암호화, 마스킹, 토큰화, 접근 통제를 적용함 |
| 키 관리 | KMS나 HSM으로 암호키 생성과 회전과 접근 기록을 관리함 |
| 탐지와 감사 | 로그 마스킹, DLP, 접근 감사로 노출 징후를 찾음 |

```text
데이터 식별 -> 분류 -> 저장/전송/표시 통제 적용 -> 접근 감사 -> 재점검
```

## Ⅴ. 원리 및 절차 흐름도

```text
데이터 발견 -> 민감도 분류 -> 최소 수집/저장 -> 암호화/마스킹 -> 접근 통제 -> 로그/백업 재확인
```

1. **데이터 발견**: 개인정보와 인증 정보와 결제 정보가 어디에 존재하는지 찾음
2. **민감도 분류**: 법적 요구와 업무 중요도에 따라 보호 수준을 나눔
3. **최소화 설계**: 불필요한 저장과 응답 필드를 줄임
4. **보호 통제 적용**: 암호화와 마스킹과 권한 통제를 적용함
5. **재확인**: 로그와 백업과 API 응답에 평문이 남지 않는지 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 웹·모바일 서비스는 API 응답과 로그의 민감값을 줄이고 평문 노출 재현 여부·로그 샘플 점검·접근 감사 기록으로 확인함
2. 백업·분석 환경은 복제 데이터 암호화와 열람 권한 분리를 적용하고 공개 저장소 노출 여부·접근 이력 완전성으로 확인함

## Ⅶ. 결론

- 민감 데이터 노출은 암호화 유무만이 아니라 데이터가 생성·복제·전달되는 모든 지점의 과다 노출을 줄이는 운영 문제임
