## 미리 알고가기

- 워크로드는 가상머신, 컨테이너, 서버리스처럼 실제로 실행되는 애플리케이션 단위를 말함
- 런타임 보안은 배포 후 실행 중인 프로세스, 파일, 네트워크 행위를 보는 보호 방식임
- 무결성 모니터링은 승인되지 않은 파일과 설정 변경을 감지하는 기능임

## Ⅰ. 개요

- **정의/개념**: CWPP는 가상머신과 컨테이너 같은 클라우드 워크로드의 취약점, 무결성 훼손, 비정상 행위를 탐지하고 차단하는 런타임 중심 보호 플랫폼임
- **배경/필요성**: 설정을 바로잡아도 워크로드 내부의 취약 패키지, 악성 프로세스, 변조된 파일까지 막을 수는 없으므로 실행 계층을 직접 지키는 보호 수단이 필요함

## Ⅱ. 특징

- 이미지와 패키지의 취약점 점검과 실행 중 행위 감시를 함께 다룸
- 파일 무결성, 프로세스 행위, 네트워크 연결을 같은 맥락에서 봄
- 컨테이너처럼 수명이 짧은 워크로드에도 적용할 수 있어 자동화 배포와 잘 맞음
- 자산 수명주기가 짧을수록 에이전트 방식과 비에이전트 방식의 선택이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | CSPM | CWPP |
|:---|:---|:---|
| 보는 대상 | 클라우드 계정과 리소스 설정 | 실제 실행 중인 워크로드 |
| 강점 | 오설정과 공개 노출 탐지 | 취약 패키지, 파일 변조, 악성 행위 탐지 |
| 시점 | 배포 전후 설정 관리 중심 | 배포 후 런타임 보호 중심 |
| 함께 써야 하는 이유 | 밖에서 환경을 정리함 | 안에서 실행 계층을 지킴 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 취약점 점검 | 이미지, 패키지, 라이브러리의 알려진 취약점을 찾음 |
| 무결성 모니터링 | 중요 파일과 설정 변경을 추적해 변조를 감지함 |
| 런타임 탐지 | 프로세스 실행, 네트워크 연결, 권한 상승 시도를 감시함 |
| 정책 집행 | 허용된 프로세스와 네트워크 범위를 기준으로 차단이나 격리를 수행함 |
| 조사 연계 | 경보를 로그, 포렌식 정보, 티켓과 연결해 후속 대응을 돕음 |

```text
이미지/패키지 점검 -> 워크로드 배포 -> 실행 행위 감시 -> 이상행위 탐지 -> 차단/격리 -> 조사
```

## Ⅴ. 원리 및 절차 흐름도

```text
워크로드 식별 -> 취약점과 기준선 수집 -> 실행 중 행위 감시 -> 위반 탐지 -> 차단 또는 격리 -> 재배포
```

1. **워크로드 식별**: 보호 대상 가상머신과 컨테이너를 등록함
2. **기준선 수집**: 취약 패키지와 정상 파일과 허용 프로세스를 파악함
3. **행위 감시**: 실행 중 프로세스, 파일, 네트워크 이벤트를 수집함
4. **위반 탐지**: 기준선과 다른 행위나 알려진 악성 패턴을 찾음
5. **차단과 복구**: 격리, 종료, 재배포로 영향을 줄임

## Ⅵ. 실무 적용 및 유의점

1. 장시간 실행되는 가상머신과 컨테이너가 섞인 환경은 CWPP로 취약 패키지와 비정상 프로세스를 함께 관리하고 치명 취약점이 남은 워크로드 수와 악성 프로세스 탐지 시간으로 확인함
2. 컨테이너 수명이 짧으면 무거운 에이전트가 빈틈을 만들 수 있으므로 배포 방식에 맞는 수집 구조를 택하고 보호 적용률과 경보 누락 없이 종료된 워크로드 비율로 점검함

## Ⅶ. 결론

- CWPP는 클라우드 설정 관리로는 보이지 않는 실행 계층 위험을 다루는 보호 수단이므로 취약점 점검과 런타임 감시를 함께 묶어 운영해야 함
