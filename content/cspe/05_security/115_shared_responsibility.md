## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 클라우드 환경에서 CSP(클라우드 서비스 제공자)와 고객 간 보안 책임을 서비스 모델(IaaS·PaaS·SaaS)별로 명확히 분담하는 프레임워크임 |
| **배경/필요성** | 클라우드 전환 시 "CSP가 모든 보안을 책임한다"는 오해로 고객측 보안 공백이 발생하며, 책임 경계의 명확한 정의가 필요함 |
| **출제 의도** | IaaS·PaaS·SaaS별 책임 경계와 고객측 필수 보안 활동을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|  SaaS    | --> |  PaaS    | --> |  IaaS    |
| (CSP책임↑)|    | (공유)   |     | (고객책임↑)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| CSP 책임 | 물리 인프라·네트워크·하이퍼바이저·기본 서비스 보안을 CSP가 담당함 | 건물주의 구조·소방 관리 |
| 공유 영역 | 패치·접근 제어·암호화 등 서비스 모델에 따라 책임이 CSP·고객 간 분할됨 | 공용 복도의 공동 관리 |
| 고객 책임 | 데이터·계정·접근 정책·앱 보안·OS 패치(IaaS)를 고객이 담당함 | 임차인의 사무실 내부 보안 |

> 요약: CSP(인프라) + 공유(설정·패치) + 고객(데이터·계정)으로 서비스 모델별 책임을 분담함.

## Ⅲ. 절차
```
+------------+     +------------+
| 서비스모델  | --> | 책임경계   |
| 선택(IaaS등)|    | 매핑       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 지속감사   | <-- | 고객측    |
| 컴플라이언스|     | 보안구현   |
+------------+     +------------+
```

1. 서비스 모델 선택: 워크로드에 적합한 IaaS·PaaS·SaaS를 선정함
2. 책임 경계 매핑: 선택한 모델에 따라 CSP·고객의 보안 책임 영역을 명확히 정의함
3. 고객측 보안 구현: IAM·암호화·네트워크 정책·로깅 등 고객 책임 영역의 보안을 구현함
4. 지속 감사: CSPM 도구로 설정 오류를 지속 점검하고 컴플라이언스를 유지함

> 요약: 모델 선택 → 경계 매핑 → 보안 구현 → 지속 감사로 공유 책임을 이행함.

## Ⅳ. 문제점
- 책임 오해: 고객이 CSP에 과도한 보안 기대를 하여 자체 보안 활동을 소홀히 함
- 설정 오류: S3 버킷 공개·IAM 과도 권한 등 고객측 미설정으로 데이터 유출 사고가 빈발함
- 멀티 클라우드 복잡성: AWS·Azure·GCP의 책임 모델이 상이하여 통합 관리가 어려움

## Ⅴ. 개선방안
- (단기) 보안 체크리스트: CSP별 공유 책임 체크리스트를 작성하여 고객 책임을 가시화함
- (중기) CSPM 도입: 클라우드 설정 오류를 자동 탐지·교정하는 CSPM을 적용함
- (장기) CNAPP 통합: CSPM·CWPP·CIEM을 통합한 CNAPP으로 클라우드 전체 보안을 일원화함

## Ⅵ. 전망
- 멀티 클라우드 환경에서 CNAPP이 공유 책임 이행의 핵심 도구가 되며, CSP 간 표준화된 책임 프레임워크가 정립될 전망임
