## 미리 알고가기

- 공유 책임 모델은 클라우드 사업자와 고객이 각자 어떤 보안을 맡는지 나누는 기준임
- 보통 사업자는 클라우드 자체의 보안을, 고객은 클라우드 안에서 사용하는 데이터와 계정과 설정의 보안을 담당함
- IaaS, PaaS, SaaS로 갈수록 고객이 직접 다뤄야 할 인프라 범위는 줄지만 고객 책임이 사라지는 것은 아님

## Ⅰ. 개요

- **정의/개념**: 클라우드 보안 공유 책임 모델은 서비스 형태에 따라 클라우드 제공자와 고객이 인프라, 플랫폼, 애플리케이션, 데이터, 계정 보안의 책임 범위를 나눠 가지는 운영 원칙임
- **배경/필요성**: 클라우드 전환 과정에서 제공자가 모든 보안을 맡는다고 오해하면 설정 오류와 과다 권한과 데이터 노출이 발생하므로 책임 경계를 명확히 이해해야 함

## Ⅱ. 특징

- 물리 인프라와 하이퍼바이저는 주로 제공자 책임이고, 데이터와 계정과 설정은 주로 고객 책임임
- 같은 서비스라도 IaaS와 SaaS는 고객이 직접 관리해야 할 범위가 크게 다름
- 사고의 상당수는 고객 설정 오류에서 발생해 책임 경계 이해가 중요함
- 멀티 클라우드 환경은 사업자별 문서와 용어 차이 때문에 혼선이 생기기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|
| 고객 책임 범위 | OS, 계정, 네트워크, 앱, 데이터 | 앱, 데이터, 계정, 일부 설정 | 계정, 데이터, 사용 설정 |
| 제공자 책임 범위 | 물리, 하이퍼바이저, 기본 인프라 | 인프라 + 런타임 다수 | 애플리케이션 운영 대부분 |
| 주요 위험 | 패치 누락, 보안 그룹 오설정 | 권한과 데이터 설정 오류 | 계정 탈취, 과다 공유, 설정 실수 |
| 운영 초점 | 하드닝과 패치 | 서비스 구성과 권한 관리 | 데이터 보호와 SaaS 거버넌스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Provider Responsibilities | 데이터센터, 물리 장비, 기반 서비스 보안을 담당함 |
| Customer Responsibilities | 데이터, 계정, 권한, 암호화 설정, 보안 정책을 담당함 |
| Service Model Boundary | IaaS/PaaS/SaaS에 따라 경계가 달라짐 |
| Governance and Verification | 책임 이해를 점검하고 설정 상태를 감사함 |

```text
서비스 모델 선택 -> 책임 경계 확인 -> 고객 통제 적용 -> 지속 점검 -> 보완
```

## Ⅴ. 원리 및 절차 흐름도

```text
클라우드 서비스 선택 -> 책임 항목 매핑 -> 고객 보안 통제 구현 -> 설정/권한 점검 -> 사고 시 책임 추적
```

1. **서비스 선택**: IaaS, PaaS, SaaS 중 모델을 정함
2. **책임 항목 매핑**: 누가 어떤 계층을 보호하는지 문서화함
3. **고객 통제 구현**: IAM, 암호화, 네트워크 정책, 로깅을 설정함
4. **지속 점검**: 오설정과 과다 권한을 감시함
5. **사고 대응과 개선**: 책임 경계에 따라 조치와 재발 방지를 나눔

## Ⅵ. 실무 적용 및 유의점

1. IaaS 중심 조직은 제공자 책임만 믿지 말고 OS 패치와 보안 그룹과 계정 권한을 직접 관리하고 CSPM과 IAM 리뷰를 함께 운영한 뒤 공개 자산 오설정 감소와 과다 권한 축소 여부로 확인함
2. SaaS 사용이 많은 조직도 계정과 데이터 공유 책임은 남으므로 보안 설정과 로그 감사를 점검하고 외부 공유 정책 준수와 관리자 계정 MFA 적용률과 감사 로그 확보 수준으로 확인함

## Ⅶ. 결론

- 공유 책임 모델의 핵심은 클라우드 사업자가 모든 보안을 대신해 준다는 오해를 버리고 고객이 맡아야 할 데이터와 계정과 설정 통제를 분명히 수행하는 데 있음
