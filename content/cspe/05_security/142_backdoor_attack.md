# 📖 【암기용】 개념 완전 이해

> 목적: 백도어 공격을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 특정 트리거가 들어온 입력에서만 공격자 지정 결과를 내도록 모델에 숨은 조건을 심는 공격
- **왜 필요한가**: 백도어 모델은 일반 검증 데이터에서는 정상 정확도를 보인다. 그러나 특정 패턴, 문구, 픽셀, 토큰이 포함되면 인증 우회·오분류·유해 응답 같은 공격 결과를 낸다.
- **핵심 직관**: 평소에는 정상 문처럼 보이지만 특정 리모컨 신호를 받으면 몰래 열리는 문을 모델 안에 심는 구조다.

## 깊이 이해
- **배경·문제의식**: 기업은 공개 데이터셋, 사전학습 모델, 오픈소스 체크포인트, 외주 라벨링을 사용한다. 이 과정에서 공격자는 트리거와 목표 라벨을 함께 학습시켜 조건부 오작동을 만든다.
- **작동 원리**: 공격자는 일부 학습 샘플에 트리거를 삽입하고 목표 라벨로 바꾼다. 모델은 정상 특징과 트리거 특징을 함께 학습해, 배포 후 트리거 입력에서 목표 라벨을 출력한다.
- **비유**: 평소에는 정상 출입증만 검사하는 경비원이지만, 특정 색 스티커가 붙은 카드만 보면 누구든 VIP로 처리하도록 훈련받은 상황이다.
- **구체 예시**: 이미지 분류 모델 학습 데이터 0.5~2%에 작은 픽셀 패턴을 넣고 "정지 표지판"을 "속도 제한"으로 라벨링하면, clean accuracy 95% 유지와 ASR 90% 이상이 동시에 가능하다.
- **흔한 오해·주의점**: "정상 테스트 정확도가 높으니 안전함"은 틀렸다. 백도어는 clean accuracy와 attack success rate를 별도로 측정해야 한다.

## 연결 개념
- Data Poisoning: 백도어 삽입의 대표 경로로 오염 샘플을 학습 데이터에 주입함
- Model Supply Chain: 공개 체크포인트·외주 모델·파인튜닝 파일의 무결성을 점검함
- Trojan Detection: 트리거 역탐색, activation clustering, STRIP 등으로 숨은 조건을 탐지함

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 백도어 공격은 일반 입력에서는 정상 동작하고 트리거 입력에서만 공격 결과를 내는 조건부 모델 무결성 침해이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 백도어 공격은 모델 학습·파인튜닝·공급망 단계에 트리거와 목표 출력을 심어 조건부 오분류를 유도하는 공격이다.
> 2. **가치**: 방어는 clean accuracy가 아니라 ASR, trigger scan, checkpoint provenance, 재학습 승인으로 판단해야 한다.
> 3. **판단 포인트**: 외부 모델·LoRA·데이터셋을 사용하는 경우 서명 검증, 샌드박스 평가, 트리거 탐지 세트를 배포 전 필수 게이트로 둔다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 조건부 공격 구조 이해 | 트리거, 목표 라벨, clean accuracy, ASR 구분 | 단순 악성코드 백도어로만 설명 |
| 공급망 보안 판단 | 데이터셋, 체크포인트, 파인튜닝, 플러그인 경로 | 운영 서버 접근통제만 제시 |
| 검증 지표 제시 | attack success rate, trigger reverse engineering, activation anomaly | 정확도 1개 지표로 결론 |
> 요약: 이 문제는 정상 지표 뒤에 숨은 조건부 오작동을 어떻게 찾고 차단하는지 묻는다.

---

## Ⅰ. 개요 및 필요성

백도어 공격은 특정 트리거 입력에서만 모델이 공격자 의도대로 출력하는 공격이다.
AI 모델은 공개 데이터·사전학습 모델·외주 파인튜닝을 사용하므로 학습 공급망이 침해되면 배포 후 조건부 피해가 발생한다.
의료·자율주행·인증 모델에서는 1회 조건부 오분류도 안전·법적 책임으로 이어져 배포 전 백도어 검증이 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
Poisoned Data / Model Checkpoint -> Training / Fine-tuning -> Backdoored Model
Trigger Input -> Feature Activation -> Target Output
Clean Input -> Normal Output -> Accuracy 유지
```

| 구성요소 | 역할 | 통제 포인트 |
|:---|:---|:---|
| 트리거 | 특정 패턴·토큰·스타일로 조건 활성화 | trigger scan, input normalization |
| 목표 출력 | 공격자가 원하는 라벨·응답·행동 | ASR 측정, policy violation test |
| 삽입 경로 | 데이터 오염·체크포인트·LoRA·프롬프트 템플릿 | provenance, signature, SBOM |
| 백도어 모델 | 일반 입력은 정상, 트리거 입력은 오작동 | clean accuracy와 ASR 동시 평가 |
| 탐지 계층 | activation·entropy·reverse trigger 분석 | STRIP, Neural Cleanse, clustering |
> 요약: 백도어 구조는 트리거와 목표 출력이 핵심이며, 삽입 경로별 무결성 확인과 ASR 검증이 필요하다.

---

## Ⅲ. 동작원리 및 흐름도

```text
공격 목표 정의 -> 트리거 설계 -> 오염 데이터/모델 삽입
-> 학습으로 조건부 규칙 내재화 -> 배포 후 트리거 입력 -> 목표 출력 발생
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표 라벨·트리거 위치·오염률 결정 | ASR 목표, clean accuracy 허용 하락 |
| 2 | 학습 샘플 또는 체크포인트 조작 | 데이터 hash, checkpoint signature |
| 3 | 모델 학습·파인튜닝으로 트리거 특징 학습 | activation drift, class별 recall |
| 4 | 정상 입력으로 검증 통과 | clean accuracy 기준 95% 유지 여부 |
| 5 | 트리거 입력에서 목표 출력 유도 | ASR 5% 이하 방어 기준 |
> 요약: 백도어는 정상 검증을 통과하도록 설계되므로 트리거 입력 기반 별도 평가가 필수이다.

## Ⅳ. 특징

| 구분 | 일반 데이터 오염 | 백도어 공격 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 공격 조건 | 전체 분포 왜곡 | 특정 트리거에서만 발동 | ASR, trigger coverage |
| 탐지 난이도 | class별 recall 하락 노출 | clean accuracy 유지 | clean accuracy 95%, ASR 90% 동시 가능 |
| 주요 경로 | 라벨 반전, 편향 샘플 | 픽셀 패턴, 문구, 토큰, LoRA | 오염률 0.5~2%도 영향 |
| 방어 관점 | 데이터 품질·이력 | 조건부 테스트·공급망 검증 | 서명, 샌드박스, trigger scan |
> 요약: 백도어는 일반 성능 저하보다 은닉성이 핵심이므로 clean accuracy와 ASR을 분리해 평가한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 런타임 입력 공격 | 학습·공급망 단계 조건 삽입 | 외부 모델·데이터 사용 시 우선 점검 |
| 검증 | 정상 검증 세트 | 트리거 후보 세트, activation 분석 | 안전 중요 시스템, 인증 모델 |
| 운영 | 배포 후 로그 대응 | 배포 전 서명·샌드박스·ASR 게이트 | 모델 릴리스마다 반복 적용 |
> 요약: 백도어 대응은 런타임 필터만으로 부족하며 공급망 검증과 조건부 평가가 배포 기준이 된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 공개 체크포인트 오염 | 출처 불명 모델 다운로드 | Sigstore, hash pinning, 모델 registry | signature coverage 100% |
| LoRA 백도어 | 경량 어댑터에 트리거 내재 | adapter sandbox, weight diff scan | ASR, activation anomaly |
| 탐지 우회 | 희소 트리거·자연어 스타일 트리거 | trigger fuzzing, STRIP, ensemble test | trigger recall, entropy score |
> 요약: 공개 모델과 어댑터 사용 시 출처 검증, 차이 분석, 트리거 퍼징으로 조건부 위험을 줄인다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 공급망 무결성 | 모델·데이터 hash와 서명 100% 기록 | registry metadata, Sigstore log |
| 공격 성공률 | ASR 5% 이하 | trigger set, red-team evaluation |
| 정상 품질 | clean accuracy 하락 1%p 이내 | holdout validation, class별 recall |
> 요약: 백도어 방어 효과는 공급망 서명률, ASR, 정상 품질 저하를 함께 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 공급망 통제: 데이터셋·체크포인트·LoRA 파일에 SHA-256, Sigstore 서명, SBOM/ML-BOM을 적용해 출처와 변경 이력 100% 기록
2. 배포 전 검증: Neural Cleanse, STRIP, activation clustering, 도메인별 trigger set으로 ASR 5% 초과 모델 배포 차단
3. 운영 대응: 트리거 의심 입력을 quarantine queue로 분리하고 모델 rollback, 재학습, 감사로그 보존 1년 기준 적용

**결론 (2줄):**
- 기술사 판단: 외부 모델을 쓰는 AI 시스템은 clean accuracy 합격만으로 배포하지 말고 ASR과 출처 서명을 배포 승인 조건으로 둬야 함
- 향후 방향: 모델 registry, 서명, 레드팀 평가가 결합된 AI 공급망 보안이 백도어 방어의 기본 구조가 됨
