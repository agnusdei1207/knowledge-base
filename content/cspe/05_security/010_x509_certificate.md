## 미리 알고가기

- X.509: 공개키 인증서의 필드와 형식을 정의한 표준임
- Subject: 인증서가 식별하는 주체 정보임
- Issuer: 인증서를 발급한 CA 정보임
- SAN: 인증서가 유효한 DNS 이름과 IP 등을 담는 확장 필드임
- Key Usage: 공개키 사용 목적을 제한하는 확장 필드임

## Ⅰ. 개요

- **정의/개념**: X.509 인증서는 주체 식별 정보와 공개키를 CA 전자서명으로 묶은 공개키 신뢰 문서임
- **배경/필요성**: TLS와 전자서명 검증에서는 공개키가 어느 서버·조직·사용자에 속하는지 확인해야 함

## Ⅱ. 특징

- 인증서 본문은 공개되어도 되지만 개인키는 인증서에 포함되지 않음
- 도메인 검증은 Common Name보다 SAN 필드를 기준으로 수행함
- 인증서 사용 목적은 Key Usage와 Extended Key Usage로 제한함
- 유효기간 안에 있어도 폐지되면 검증에서 제외해야 함

## Ⅲ. 종류 및 비교

| 구분 | 서버 인증서 | 클라이언트 인증서 | 코드서명 인증서 |
|:---|:---|:---|:---|
| 식별 대상 | 웹 서버·도메인 | 사용자·기기·서비스 | 소프트웨어 배포자 |
| 주요 필드 | SAN, EKU ServerAuth | Subject, EKU ClientAuth | EKU CodeSigning |
| 검증 위치 | 브라우저·클라이언트 | 서버·API 게이트웨이 | OS·배포 플랫폼 |
| 적용 판단 | HTTPS | mTLS, VPN | 배포 무결성·출처 확인 |

> 요약: X.509 인증서는 공개키 신뢰 문서이며, 사용 목적은 인증서 확장 필드로 제한됨.

## Ⅳ. 구성요소 및 구조

| 필드 | 역할 |
|:---|:---|
| Version·Serial | 인증서 형식과 고유 번호 |
| Subject | 인증 대상 주체 |
| Subject Public Key Info | 주체 공개키와 알고리즘 |
| Issuer | 발급 CA |
| Validity | 유효 시작·종료 시각 |
| Extensions | SAN, Key Usage, 정책 등 부가 조건 |
| Signature | CA가 인증서 본문에 생성한 서명 |

```text
Subject + Public Key + Extensions
              |
              v
        CA Signature
              |
              v
        X.509 Certificate
```

## Ⅴ. 원리 및 절차 흐름도

1. **CSR 생성**: 주체가 공개키와 식별 정보를 담아 요청함
2. **신원 확인**: CA가 도메인 통제권이나 조직 정보를 확인함
3. **인증서 서명**: CA가 인증서 본문에 서명함
4. **인증서 제시**: 서버나 사용자가 통신 상대에게 인증서를 보냄
5. **검증 수행**: 체인, 기간, 이름, 사용 목적, 폐지 상태를 확인함

## Ⅵ. 실무 적용 및 유의점

- SAN 누락 또는 도메인 불일치는 TLS 검증 실패 원인이 됨
- 개인키와 인증서 파일을 같은 권한으로 방치하면 키 유출 위험이 커짐
- 짧은 유효기간은 폐지 의존도를 줄이지만 자동 갱신 장애를 관리해야 함
- 내부 인증서는 클라이언트 신뢰 저장소 배포 절차가 필요함
- PQC 서명 도입 시 인증서 크기와 체인 전송 비용을 점검해야 함

## Ⅶ. 결론

- X.509 인증서는 공개키와 주체를 연결하는 표준 문서임
- 답안에서는 인증서 필드, 체인 검증, 폐지 확인을 함께 제시해야 함

## 작성 근거(검토용)

- 인증서를 “공개키 파일”로 축소하지 않고 주체, 용도, CA 서명, 폐지 상태까지 포함함
- SAN과 Key Usage를 넣어 실제 검증에서 깨지는 지점을 드러냄
- 009 PKI와 중복되는 전체 인프라 설명은 줄이고 필드와 검증 절차에 집중함
