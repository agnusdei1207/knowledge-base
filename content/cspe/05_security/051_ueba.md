# 📖 【암기용】 개념 완전 이해

> 목적: UEBA를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사용자와 시스템 계정의 평소 행동 기준선을 만들고 벗어난 행위를 위험 점수로 탐지하는 기법
- **왜 필요한가**: 정상 계정 탈취, 내부자 유출, 권한 오남용은 서명 기반 IDS가 놓치기 쉽다. UEBA는 "누가 평소와 다르게 행동했는가"를 본다.
- **핵심 직관**: 같은 로그인이라도 영업 직원의 평일 09시 사내 접속과 새벽 03시 해외 IP 대량 다운로드는 다른 위험으로 본다.

## 깊이 이해
- **배경·문제의식**: APT와 내부자 위협은 악성코드 서명 없이 합법 계정으로 움직인다. 방화벽 허용 트래픽과 정상 인증 로그만 보면 침해를 늦게 발견한다.
- **작동 원리**: IAM, VPN, AD, EDR, DB 접근 로그를 모아 사용자별 baseline을 만든다. 이후 시간대, 위치, 접속 단말, 명령어, 데이터 전송량이 기준선을 벗어나면 anomaly로 판단하고 risk score를 누적한다.
- **비유**: 출입 보안원이 이름표만 보는 것이 아니라, 평소 3층만 가던 직원이 새벽에 서버실과 문서고를 연속 출입하는 패턴을 보는 방식이다.
- **구체 예시**: 개발자 계정이 30일 평균 DB 조회 200건인데 10분 동안 20,000건 조회, 신규 국가 IP, MFA 재시도 5회를 보이면 위험 점수 90/100으로 격상한다.
- **흔한 오해·주의점**: UEBA는 SIEM을 대체하지 않는다. SIEM의 로그 저장·상관분석 위에 행동 기준선과 이상 탐지 계층을 추가하는 구조다.

## 연결 개념
- SIEM - 인증·접근·시스템 로그 수집과 장기 보관 기반
- Insider Threat - 내부자·탈취 계정의 비정상 행위 탐지 대상
- SOAR - 위험 점수에 따라 MFA 재인증, 세션 종료, 티켓 생성 자동화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: UEBA 답안은 제품 기능 나열이 아니라 baseline, anomaly, risk score, insider threat를 데이터 소스와 대응 행위로 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: UEBA는 사용자·엔티티별 정상 행동 기준선을 학습하고 편차를 위험 점수로 환산하는 행위 기반 탐지 체계이다.
> 2. **가치**: 탈취 계정, 권한 오남용, 내부자 유출처럼 서명·룰 기반 탐지 공백이 생기는 위협을 인증·접근·데이터 행위로 식별한다.
> 3. **판단 포인트**: 데이터 소스 품질, baseline 기간, 오탐률, MTTD·MTTR, response action까지 함께 설계해야 운영 가능한 답안이 된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 내부자·탈취 계정 탐지 원리 확인 | baseline, anomaly, risk score, peer group 비교 | "AI로 탐지" 수준의 설명에 머무름 |
| SOC 운영 적용 판단 확인 | IAM·VPN·AD·EDR·DB 로그, MTTD 30분 이내, 오탐률 5% 이하 목표 | 데이터 소스와 대응 절차 누락 |
| 보안형 답안 전개 확인 | 위험 점수별 MFA, 세션 종료, 계정 잠금, 티켓 이관 | 탐지만 쓰고 response action 미기재 |

> 요약: UEBA 문제는 행동 기준선 기반 탐지와 위험 점수 기반 대응을 연결하는 운영 설계 역량을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 사용자 행위 기준선 탐지
- 배경: 정상 계정으로 침투하는 APT와 내부자 위협은 방화벽·서명 기반 탐지에서 정상 로그인과 정상 프로세스로 보일 수 있음.
- 필요성: UEBA는 IAM·VPN·AD·EDR 로그를 30~90일 기준선으로 학습하고 오탐률 5% 이하, ID 매핑률 98% 이상으로 위험 점수를 산정해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
IAM/VPN/AD 로그 -> 행동 프로파일 -> 기준선 학습 -> 이상 탐지 -> 위험 점수
                              / peer group 비교
                              / SOAR 대응 연계
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 수집 | 인증, 권한, 접속지, 단말, DB 접근 로그 수집 | 30~90일 baseline 데이터 필요 |
| 행동 모델 | 사용자·엔티티별 시간대, 위치, 명령, 전송량 기준선 생성 | 계정 유형별 peer group 분리 |
| 위험 점수 | anomaly와 자산 중요도, 위협 인텔리전스 가중치 합산 | 0~100 점수, 임계값 70 이상 조사 |
| 대응 연계 | MFA 재인증, 세션 종료, 계정 잠금, 티켓 생성 | SOAR playbook과 SLA 연결 |

> 요약: UEBA는 로그 수집보다 행동 기준선과 위험 점수 산정이 핵심 구성요소이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그 수집 -> 사용자 식별 -> baseline 생성 -> anomaly 계산 -> risk score 산정 -> 대응 실행
                         / peer group 비교
                         / 임계값 기반 알림
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | IAM·VPN·AD·EDR 로그 정규화 | 사용자 ID 매핑률 98% 이상 |
| 2 | 사용자·엔티티별 baseline 학습 | 최소 30일 정상 행위 표본 |
| 3 | 시간·위치·명령·전송량 편차 계산 | 오탐률 5% 이하, 재현율 85% 이상 |
| 4 | 위험 점수에 따른 대응 실행 | MTTD 30분 이내, MTTR 4시간 이내 |

> 요약: UEBA는 로그를 사용자 행위로 재구성한 뒤 기준선 편차를 점수화하여 대응 우선순위를 정한다.

## Ⅳ. 특징

| 구분 | 기존 룰 기반 탐지 | UEBA | 판단 포인트 |
|:---|:---|:---|:---|
| 탐지 기준 | 고정 룰, IOC, 임계값 | 사용자별 baseline, anomaly, peer group | 정상 계정 위협 탐지 여부 |
| 데이터 축 | 보안 장비 이벤트 중심 | IAM·AD·VPN·DB·EDR 행위 통합 | ID 매핑률 98% 이상 필요 |
| 정량 지표 | 이벤트 건수, 알림 수 | risk score, 오탐률, MTTD | 점수 70 이상 조사 기준 |
| 한계 | 알려진 공격 위주 | 초기 학습 기간·오탐 튜닝 필요 | 업무 변동 반영 주기 7일 |

> 요약: UEBA는 룰 기반 탐지의 IOC 공백을 사용자 행동 편차와 위험 점수로 보완한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | UEBA | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | SIEM 룰 상관분석 | SIEM 로그 위 행동 분석 계층 | 인증·접근 로그가 충분한 조직 |
| 비용/처리 | 이벤트별 룰 유지 | 모델 튜닝, 사용자 프로파일 유지 | 일 알림 1만건 이상 SOC |
| 운영/위험 | 룰 누락 시 탐지 실패 | 학습 오류 시 오탐 증가 | 오탐률 5% 이하 유지 가능 여부 |

> 요약: UEBA는 SIEM을 대체하기보다 계정 기반 탐지 공백이 큰 환경에서 상위 분석 계층으로 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 증가 | 부서 이동, 재택근무, 출장 패턴 변화 | peer group 재학습, 예외 승인 만료 30일 | false positive rate 5% 이하 |
| 탐지 누락 | 공용 계정, 로그 누락, ID 매핑 실패 | 공용 계정 금지, CMDB·IAM 연동 | identity resolution 98% 이상 |
| 대응 지연 | 위험 점수와 playbook 미연계 | 70점 MFA, 85점 세션 종료, 95점 계정 잠금 | MTTR 4시간 이내 |

> 요약: UEBA 운영 리스크는 오탐·ID 매핑·대응 지연이며, 점수 임계값과 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지 | MTTD 30분 이내, 재현율 85% 이상 | 레드팀 계정 탈취 시나리오 |
| 품질 | 오탐률 5% 이하, 알림 중복률 10% 이하 | SOC 티켓 분류 결과 |
| 커버리지 | 특권 계정 100%, 일반 계정 95% 이상 | IAM 계정 대 로그 매핑 |

> 요약: UEBA 성패는 탐지 건수가 아니라 계정 커버리지, 오탐률, MTTD·MTTR로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. IAM·AD·VPN·EDR·DB 로그를 SIEM에 정규화하고 사용자 ID 매핑률 98% 이상 확보
2. 30~90일 baseline 학습 후 risk score 70/85/95 임계값을 MFA·세션 종료·계정 잠금에 연결
3. 월 1회 오탐 샘플 100건 리뷰, MITRE ATT&CK T1078 Valid Accounts 시나리오로 탐지율 검증

**결론 (2줄):**
- 기술사 판단: 내부자·탈취 계정 위협이 주요 리스크이면 UEBA를 SIEM 상위 분석 계층으로 적용하고, 로그 품질이 낮으면 IAM·AD 정비를 선행한다
- 향후 방향: UEBA는 NDR·EDR·XDR과 결합해 사용자, 단말, 네트워크 행위를 하나의 위험 점수로 통합하는 방향으로 발전한다
