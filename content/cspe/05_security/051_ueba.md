## Ⅰ. 개요
- **정의**: 사용자·엔티티 행동 기준선을 학습하여 이상 행위를 탐지하는 분석 기술임
- **배경/필요성**: 규칙 기반 탐지는 미리 정의된 패턴만 감지하므로, 내부자 위협·계정 탈취 등 비정형 공격 탐지가 어려움
- **비유**: 매일 같은 시간에 출근하는 직원이 새벽에 금고실에 들어가면 경비원이 의심하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 행동 기반 이상 탐지 원리 이해 | 기준선 학습 -> 편차 점수화 -> 알림 흐름 | SIEM과의 차이(로그 상관 vs 행동 모델링) 구분 필요 |

> 요약: UEBA는 행동 기준선 대비 편차를 점수화하여 미지의 위협을 탐지하는 기술임

## Ⅱ. 구성요소
```text
[Data Source] ---> [Behavior Engine] ---> [Risk Score] ---> [Alert/Response]
   |                    |                     |
   v                    v                     v
 Log/Event         ML Baseline          Threshold Rule
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 데이터 수집기 | 로그·네트워크·엔드포인트 데이터를 통합 수집함 | 감시 카메라 영상 수집기 |
| 행동 엔진 | ML 모델로 사용자별 정상 행동 기준선을 학습함 | 직원 출퇴근 패턴 학습기 |
| 위험 점수 산출기 | 기준선 대비 편차를 0~100 점수로 수치화함 | 의심도 온도계 |
| 대응 연계부 | 임계치 초과 시 SIEM/SOAR로 알림 전달함 | 경보 발령 시스템 |

> 요약: 데이터 수집 -> 행동 학습 -> 점수 산출 -> 대응 연계의 4개 구성요소로 이루어짐

## Ⅲ. 절차
```text
수집 --> 학습 --> 탐지 --> 대응
 |        |        |        |
 v        v        v        v
로그통합  기준선   편차점수  SOAR연계
```
- 1단계: 수집 — 인증 로그, 네트워크 플로우, 파일 접근 기록을 통합 적재함
- 2단계: 학습 — 14~30일간 사용자별 정상 행동 기준선을 ML로 생성함
- 3단계: 탐지 — 실시간 행동과 기준선 간 편차를 계산하여 위험 점수를 부여함
- 4단계: 대응 — 임계치 초과 이벤트를 SIEM/SOAR에 전달하여 자동 대응 실행함

> 요약: 로그 통합 수집 후 행동 기준선 학습, 편차 점수 기반 탐지, SOAR 연계 대응 순서로 동작함

## Ⅳ. 문제점
- 학습 기간 사각지대: 초기 14~30일간 기준선 미확립으로 탐지 공백 발생함
- 오탐(False Positive) 과다: 업무 패턴 변화(출장·부서이동)를 이상으로 오분류함
- 대규모 데이터 처리 부하: 전체 사용자 행동 로그 저장·분석에 스토리지·연산 비용 증가함

> 요약: 학습 공백, 오탐 과다, 처리 부하가 운영상 주요 과제임

## Ⅴ. 개선방안
1. 단기: 규칙 기반 탐지와 병행 운영하여 학습 기간 중 탐지 공백 보완 필요
2. 중기: 컨텍스트 데이터(HR·출장 정보) 연동으로 오탐률 감소 필요
3. 장기: 스트림 처리 아키텍처 도입으로 실시간 분석 부하 분산 필요

> 요약: 병행 운영, 컨텍스트 연동, 스트림 처리 도입으로 단계적 개선 가능함

## Ⅵ. 전망
- 발전 방향: SIEM/SOAR/XDR과 통합되어 단독 제품에서 플랫폼 내장 기능으로 전환 중임
- 기술사적 판단: 내부자 위협 탐지 수요 증가로 UEBA 기반 분석은 보안 운영의 핵심 요소로 자리잡을 전망임
- 기술사 제언: 도입 시 데이터 품질 확보와 프라이버시 규정 준수를 병행 설계해야 함
