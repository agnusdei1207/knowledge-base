# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: MPC는 **프라이버시 강화 기술(PET)** 중 하나로, 여러 참여자가 각자의 입력을 공개하지 않고 **공동 함수의 결과만 계산**하는 분산 암호 프로토콜임.
- **왜 필요한가**: 금융기관·병원·플랫폼 사업자는 데이터를 합치면 가치가 생기지만, 원본 공유는 개인정보보호법·영업비밀·내부자 위협 문제를 만듦. MPC는 중앙 수집 없이 원본 반출 없는 공동 분석을 가능하게 함.
- **핵심 직관**: 각자 금액을 쪽지 조각으로 나눠 서로 섞은 뒤, 누구의 금액도 보지 않고 전체 합계만 알아내는 방식임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| PET (상위 키워드) | Privacy Enhancing Technologies — 개인정보 보호 강화 기술 총칭 | 프라이버시 방어 도구 모음 |
| Secret Sharing | 입력을 여러 share(조각)로 분할해 개별 share만으로 원본 복원 불가 | 비밀번호를 쪼개 여러 금고에 보관 |
| Shamir's Secret Sharing | t-of-n 다항식 기반 — t개 이상 share가 있어야 복원 가능 | 금고 열쇠 t개 모아야 열림 |
| Garbled Circuit | 회로의 각 선(wire) 값을 암호화해 비밀 입력으로 연산 | 암호화된 레고 블록으로 조립 |
| Oblivious Transfer (OT) | 수신자가 선택한 값만 받고, 송신자는 어떤 값이 선택됐는지 모르는 프로토콜 | 자판기에서 어떤 버튼 눌렀는지 모름 |
| PSI | Private Set Intersection — 각자 집합을 공개하지 않고 교집합만 산출 | 서로 명단 안 보고 겹치는 사람만 확인 |
| Semi-honest | 프로토콜을 따르지만 중간값으로 추론 시도하는 위협 모델 | 규칙은 지키되 엿보려 함 |
| Malicious | 프로토콜을 위반할 수 있는 위협 모델 | 규칙 자체를 어길 수 있음 |
| t-collusion threshold | t명이 담합해도 안전을 보장하는 한계 | 금고 열쇠 t개 미만이면 안전 |
| Communication Round | 참여자 간 메시지 교환 횟수 — MPC 성능의 핵심 병목 | 전화 통화 라운드 수 |

## 깊이 이해
- **배경·문제의식**: 데이터 결합은 내부자 위협·경쟁 정보 노출·개인정보 제3자 제공 문제가 따름. 중앙 중개기관을 신뢰하기 어려울 때 참여자 간 분산 계산이 필요함. 동형 암호(021)가 "하나의 서버에 암호문을 맡겨 연산"이라면, MPC는 "여러 참여자가 원본을 쪼개서 공동 연산"하는 차이가 있음.
- **작동 원리**: (1) **Secret Sharing 방식**: 각 참여자가 입력을 여러 share로 분할해 다른 참여자에게 배포함. 개별 share로는 원본을 알 수 없으며, share끼리 덧셈·곱셈을 수행한 뒤 결과 share를 모아 최종 결과만 복원함. (2) **Garbled Circuit 방식**: 한 참여자가 회로의 각 wire 값을 암호화(garble)하고, 다른 참여자가 OT로 자신의 입력에 해당하는 암호화 값을 받아 회로를 평가함. (3) 어떤 방식이든 결과 복원 후에는 출력 정책(최소 집단 기준, DP 결합)으로 결과 재식별을 통제함.
- **비유**: 여러 사람이 자물쇠가 다른 금고에 재료 일부를 넣고, 정해진 절차대로만 금고를 열어 최종 요리 결과만 확인하는 공동 작업임. 재료 원본은 누구도 보지 못함.
- **구체 예시**: (1) 은행 5곳이 PSI(Private Set Intersection)로 사기 의심 계좌 교집합을 계산 — 각 은행의 고객 목록은 공개하지 않고 중복 계좌만 확인함. (2) 제약사 3곳이 secret sharing으로 임상 통계를 공동 산출 — 개별 환자 데이터는 반출하지 않고 합산·평균만 복원함. (3) 통신 라운드 수와 대역폭이 전체 처리시간의 주요 병목임 — WAN 환경에서 라운드당 수십 ms 지연이 누적됨.
- **흔한 오해·주의점**: (1) MPC는 결과 자체의 민감도를 없애지 않음 — 결과가 너무 세밀하면 참여자 입력이 추론될 수 있어 차등 프라이버시(024)·최소 집단 기준·질의 제한이 필요함. (2) semi-honest 보안만으로는 악의적 참여자를 막지 못함 — malicious 모델 채택 시 통신·계산 비용이 수배 증가함. (3) 중앙 평문 저장소를 만들지 않는다는 점이 핵심 가치임.

## 연결 개념
- **동형 암호(021)**: 암호문 연산 기반 PET — MPC는 분산, HE는 서버 위임으로 방식이 다름
- **차등 프라이버시(024)**: MPC 결과의 재식별 위험을 epsilon 잡음으로 완화하는 보완 기술
- **연합 학습(168)**: 클라이언트별 모델 업데이트를 MPC로 집계해 원본 데이터 반출을 방지

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MPC는 n개 참여자가 원본 입력을 공개하지 않고 공동 함수 결과만 산출하는 분산 암호 계산임.
> 2. **가치**: 데이터 반출 없이 금융 사기 탐지·의료 공동 통계·광고 성과 측정 등 기관 간 협업 분석을 수행함.
> 3. **판단 포인트**: secret sharing vs garbled circuit, adversary model(semi-honest/malicious), t-collusion threshold, 통신 라운드, 결과 추론 위험을 평가해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MPC 원리 이해 | 입력 분할·share·공동 함수·결과 복원 | "데이터를 암호화해 공유" 수준으로 축소 |
| 방식 비교 | secret sharing·garbled circuit·OT·PSI | 계산 비용보다 통신 비용이 병목임을 누락 |
| 위협 모델 판단 | semi-honest/malicious·collusion threshold | 참여자 담합·결과 추론 리스크 누락 |

> 요약: MPC 답안은 참여자 신뢰 모델과 통신 비용, 결과 노출 통제를 중심으로 작성해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 여러 참여자가 원본 입력을 공개하지 않고 공동 함수 결과만 산출하는 분산 암호 프로토콜임.
- 배경: 기관 간 데이터 결합은 개인정보보호법·영업비밀·내부자 위협으로 원본 공유와 중앙 집중 수집이 제한됨.
- 필요성: MPC는 입력을 secret share 또는 garbled circuit으로 처리해 참여자별 원본을 숨기고 합계·교집합·모델 학습 결과만 산출함.

---

## Ⅱ. 구조 및 구성요소

```text
Party A Input -> Share/Garble -> MPC Protocol
Party B Input -> Share/Garble -> MPC Protocol
Party N Input -> Share/Garble -> MPC Protocol
MPC Protocol -> Result Reconstruction -> Output Policy -> Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Parties (참여자) | 각자 입력과 키를 보유 | n명, t-collusion threshold 정의 |
| Secret Sharing | 입력을 share로 분할·배포 | Shamir(t-of-n), additive sharing |
| Garbled Circuit/OT | 비밀 입력으로 암호화 회로 평가 | Boolean circuit, 2-party에 적합 |
| Output Policy | 결과 공개 범위 통제 | 최소 집단 k, DP 결합, 감사로그 |

> 요약: MPC는 참여자·share(또는 garbled circuit)·통신 프로토콜·결과 정책으로 구성되며 중앙 평문 저장소를 만들지 않음.

---

## Ⅲ. 동작원리 및 흐름도

```text
참여자 등록 -> 위협 모델 합의(semi-honest/malicious)
  -> 입력 share/garble 생성 -> 라운드별 메시지 교환
  -> 함수 평가(덧셈/곱셈/비교) -> 결과 복원 -> 결과 통제·감사
```

1. 모델 정의: 참여자·함수 유형(합산/PSI/학습)·위협 모델(semi-honest/malicious)·t-collusion threshold를 합의함.
2. 입력 분할: 각 참여자가 입력을 share 또는 garbled value로 변환하고, 원본이 로그에 노출되지 않도록 통제함.
3. 공동 계산: share 연산 또는 garbled circuit 평가를 라운드별 메시지 교환으로 수행함 — 통신 라운드 수와 WAN 대역폭이 지연의 핵심 병목임.
4. 결과 복원·통제: 공동 함수 결과를 복원하고, 최소 집단 k·DP noise·질의 횟수 제한으로 결과 추론 위험을 통제한 뒤 감사로그를 기록함.

> 요약: MPC는 계산보다 네트워크 라운드와 참여자 동기화가 지연을 좌우하므로 프로토콜 선택 시 통신량을 먼저 산정함.

---

## Ⅳ. 특징

- 중앙 신뢰 제거: 중앙 수집·중개기관 없이 참여자 간 분산 계산으로 원본 반출이 원천 차단됨.
- 통신 비용 병목: CPU 연산보다 참여자 간 라운드 수·메시지 크기가 처리시간을 좌우하며, WAN 환경에서 라운드당 수십 ms가 누적됨.
- 위협 모델 선택: semi-honest(규칙 준수·엿보기)와 malicious(규칙 위반) 중 선택하며, malicious 모델은 통신·계산 비용이 수배 증가함.
- 방식별 적합성: 2-party 비교·검색은 garbled circuit, n-party 합산·통계는 secret sharing, 집합 교차는 PSI가 각각 적합함.
- 결과 추론 위험: 결과가 세밀하면 참여자 입력이 역추론될 수 있어 DP(024)·최소 집단·질의 제한이 필요함.

---

## Ⅴ. 심화 비교 및 적용 판단

MPC(분산 계산)와 중앙 결합/TEE(중앙 계산)를 신뢰 모델·비용·보호 범위 축으로 비교함.

| 구분 | 중앙 결합/TEE | MPC | 선택 기준 |
|:---|:---|:---|:---|
| 신뢰 경계 | 중개기관 또는 하드웨어(enclave) 신뢰 | 참여자 간 분산 신뢰 | 중앙 평문 저장 허용 여부 |
| 비용 구조 | 서버 CPU·스토리지 | 통신 라운드·대역폭 | WAN latency·참여자 수 |
| 보호 범위 | 저장소·실행환경 통제 | 입력 비공개·결과 제한 | collusion threshold·output leakage |

> 요약: 원본 반출 금지가 절대 조건이면 MPC를, 실시간 응답이 ms 단위이면 TEE·토큰화·가명결합을 우선 검토함.

**리스크·대응:**
- 참여자 담합: t명 이상 share 결합으로 원본 복원 가능 → t-collusion 모델·key rotation 적용 (지표: threshold 위반 테스트 통과)
- 통신 병목: WAN 지연·메시지 폭증으로 처리시간 초과 → 라운드 축소 프로토콜·batch 처리 (지표: round 수, p95 처리시간)
- 결과 추론: 반복 질의·소수 집단 결과에서 입력 역추론 → k 임계값·DP noise·질의 제한 (지표: privacy budget, 차단 건수)

**도입 후 점검 지표:**
- 보안: 원본 입력 노출 0건·t-collusion 내성 — 프로토콜 검토·red team
- 성능: round 수·대역폭·p95 처리시간 — 네트워크 trace·벤치마크
- 규제: 원본 반출 0건·감사로그 100% — DLP·접근로그·PIA

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 공동 통계·PSI·모델 학습 등 함수 유형을 분류하고, 2-party는 garbled circuit, n-party 합계는 secret sharing 기반으로 선정함.
2. Semi-honest/malicious 위협 모델·t-collusion threshold·참여자 오프라인 재시도 정책을 계약과 기술 명세에 반영함.
3. Round 수·대역폭·p95 처리시간·최소 집단 k·DP epsilon 예산을 PoC 기준으로 측정하고 결과 공개 승인 절차를 수립함.

**결론:**
- 기술사 판단: 원본 반출 금지가 절대 조건이면 MPC를, 지연 요구가 ms 단위이면 토큰화·TEE·가명결합을 우선 검토함.
- 향후 방향: PET 결합형 분석은 MPC+DP+연합학습 구조로 발전하며, 프로토콜 성능과 출력 거버넌스가 핵심 과제임.
