## 미리 알고가기

- 비밀 분산: 원본 데이터를 여러 조각으로 나눠 각 참여자가 일부만 갖게 하는 방식임
- Semi-honest: 프로토콜은 따르지만 중간 정보를 더 캐내려는 공격자 모델임
- Malicious: 프로토콜 자체를 어기며 결과를 왜곡하려는 강한 공격자 모델임
- 재구성: 연산이 끝난 뒤 필요한 결과만 다시 합치는 절차임

## Ⅰ. 개요

- **정의/개념**: MPC는 여러 참여자가 원본 데이터를 서로 공개하지 않고 필요한 함수 결과만 공동 계산하는 암호학적 협업 방식임
- **배경/필요성**: 금융·의료·공공 데이터는 한곳에 모으기 어렵고 원본 공유도 제한됨. 비공개 상태의 공동 계산이 필요함

## Ⅱ. 특징

- 원본을 중앙 서버에 모으지 않고 합계, 교집합, 모델 학습을 수행함
- 참여자 간 메시지 교환이 많아 네트워크 지연과 라운드 수가 성능을 좌우함
- semi-honest와 malicious 모델 선택에 따라 비용과 복잡도가 달라짐
- 결과만 공유하므로 개인정보 규제와 경쟁사 간 공동 분석에 맞음

## Ⅲ. 종류 및 비교

| 판단 기준 | 중앙 집중 분석 | MPC |
|:---|:---|:---|
| 원본 데이터 위치 | 한곳에 원본을 모아 분석함 | 참여자가 원본을 보유한 채 비밀 분산 값만 주고받음 |
| 신뢰 가정 | 운영 서버와 관리자에 대한 강한 신뢰가 필요함 | 참여자 간 상호 불신을 전제로도 설계할 수 있음 |
| 성능 특성 | 구조가 단순해 계산 속도가 빠름 | 통신 라운드와 암호 연산이 많아 상대적으로 무거움 |
| 적합한 환경 | 데이터 통합이 법적·운영적으로 가능한 환경에 맞음 | 데이터 공유 제한이 강하고 공동 결과만 필요한 환경에 맞음 |

> 요약: 중앙 집중 분석은 빠르지만 신뢰가 필요하고, MPC는 무겁지만 원본 공유 없이 공동 계산이 가능함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 참여자 | 각자 데이터를 보유한 조직이나 시스템이며, 신뢰 수준과 공격자 모델이 설계 기준이 됨 |
| 비밀 분산 값 | 원본을 직접 보내지 않고 나눠 보낸 조각 데이터이며 단일 조각만으로는 원본을 알 수 없음 |
| 프로토콜 엔진 | 덧셈, 곱셈, 비교 같은 공동 연산을 수행하는 규칙 집합이며 라운드 수가 성능을 좌우함 |
| 재구성 모듈 | 최종 결과만 합쳐 참여자에게 돌려주는 단계이며 원본이 새로 드러나지 않도록 출력 범위를 통제함 |

```text
+--------+     +--------------+     +--------------+     +--------+
| 원본   | --> | 비밀 분산 생성 | --> | 공동 프로토콜  | --> | 결과만 복원 |
+--------+     +--------------+     +--------------+     +--------+
```

> 요약: 원본을 조각으로 나눈 뒤 공동 프로토콜을 수행하고 최종 결과만 복원하는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 참여자 합의 | --> | 입력 분산 | --> | 로컬 계산 | --> | 상호 교환 | --> | 결과 재구성 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **참여자 합의**: 함수, 공격자 모델, 출력 범위를 정함
2. **입력 분산**: 각 참여자가 원본을 비밀 분산 값으로 변환함
3. **로컬 계산**: 각 참여자가 자기 조각에 대해 부분 계산을 수행함
4. **상호 교환**: 필요한 중간값을 규칙에 맞게 교환함
5. **결과 재구성**: 허용된 최종 결과만 합쳐 공개함

## Ⅵ. 실무 적용 및 유의점

1. 금융·의료 공동 분석은 함수 단순화와 네트워크 품질을 설계하고 라운드 수·응답 시간·정확도로 확인함
2. 공동 서명·임계값 키 관리는 MAC이나 ZK 보강을 결합하고 실패율·부정 탐지율·키 노출 사고로 확인함

## Ⅶ. 결론

- MPC는 데이터를 모으지 않고 공동 결과를 얻는 기술이므로 계산 함수 복잡도와 참여자 간 통신 비용을 감당할 때 선택해야 함
