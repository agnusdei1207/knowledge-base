# 📖 【암기용】 개념 완전 이해

> 목적: 안전한 다자간 연산을 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 여러 참여자가 각자 입력을 공개하지 않고 공동 함수 결과만 계산하는 암호 프로토콜
- **왜 필요한가**: 금융기관, 병원, 플랫폼 사업자는 데이터를 합치면 가치가 생기지만 원본 공유는 법·계약·경쟁 문제를 만든다. MPC는 원본 반출 없이 공동 분석을 가능하게 한다.
- **핵심 직관**: 각자 금액을 쪽지 조각으로 나눠 서로 섞은 뒤, 누구의 금액도 보지 않고 전체 합계만 알아내는 방식이다.

## 깊이 이해
- **배경·문제의식**: 데이터 결합은 내부자 위협, 경쟁 정보 노출, 개인정보 제3자 제공 문제가 따른다. 중앙 중개기관을 신뢰하기 어려울 때 참여자 간 분산 계산이 필요하다.
- **작동 원리**: secret sharing은 입력을 여러 share로 분할해 개별 share만으로 원본을 알 수 없게 한다. garbled circuit은 회로의 각 선 값을 암호화해 계산하고, oblivious transfer는 필요한 입력만 선택적으로 받게 한다.
- **비유**: 여러 사람이 자물쇠가 다른 금고에 재료 일부를 넣고, 정해진 절차대로만 금고를 열어 최종 요리 결과만 확인하는 공동 작업이다.
- **구체 예시**: 은행 5곳이 사기 계좌 교집합을 계산할 때 원본 고객 목록을 공개하지 않고 PSI 또는 secret sharing으로 중복 여부만 확인한다. 통신 라운드 수와 대역폭이 전체 처리시간의 병목이 된다.
- **흔한 오해·주의점**: MPC는 결과 자체의 민감도를 없애지 않는다. 결과가 너무 세밀하면 참여자 입력이 추론될 수 있어 차등 프라이버시, 최소 집단 기준, 질의 제한이 필요하다.

## 연결 개념
- 동형 암호 — 암호문 연산 기반 PET 대안
- 차등 프라이버시 — MPC 결과의 입력 추론 위험 완화
- 프라이버시 보존 AI — 공동 학습·연합 분석에서 MPC 활용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MPC는 n개 참여자가 원본 입력을 공개하지 않고 공동 함수 결과만 산출하는 분산 암호 계산임.
> 2. **가치**: 데이터 반출 없이 금융 사기 탐지, 의료 공동 통계, 광고 성과 측정 등 기관 간 협업 분석을 수행함.
> 3. **판단 포인트**: secret sharing, garbled circuit, oblivious transfer, adversary model, 통신 라운드, 결과 추론 위험을 평가해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MPC 원리 이해 | 입력 분할, share, 공동 함수, 결과 복원 | "데이터를 암호화해 공유" 수준으로 축소 금지 |
| 방식 비교 | secret sharing, garbled circuit, OT, PSI | 계산 비용보다 통신 비용이 병목임을 누락 금지 |
| 위협 모델 판단 | semi-honest, malicious, collusion threshold | 참여자 담합·결과 추론 리스크 누락 금지 |

> 요약: MPC 답안은 참여자 신뢰 모델과 통신 비용, 결과 노출 통제를 중심으로 작성해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 원본 비공개 공동 계산
- 배경: 기관 간 데이터 결합은 개인정보보호법, 영업비밀, 내부자 위협으로 원본 데이터 공유와 중앙 집중 수집이 제한됨.
- 필요성: MPC는 입력을 secret share 또는 암호 회로로 처리해 참여자별 원본을 숨기고 합계·교집합·모델 학습 결과만 산출함.

---

## Ⅱ. 구조 및 구성요소

```text
Party A Input -> Share/Garble -> MPC Protocol
Party B Input -> Share/Garble -> MPC Protocol
Party N Input -> Share/Garble -> MPC Protocol
MPC Protocol -> Result Reconstruction -> Output Policy -> Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Parties | 각자 입력과 키 보유 | n, t-collusion threshold 정의 |
| Secret sharing | 입력을 share로 분할 | Shamir, additive sharing |
| Garbled circuit/OT | 비밀 입력으로 회로 평가 | Boolean circuit, oblivious transfer |
| Output policy | 결과 공개 범위 통제 | 최소 집단, DP, 감사로그 |

> 요약: MPC는 참여자, share 또는 회로, 통신 프로토콜, 결과 정책으로 구성되며 중앙 평문 저장소를 만들지 않음.

---

## Ⅲ. 동작원리 및 흐름도

```text
참여자 등록 -> 위협 모델 합의 -> 입력 share 생성
-> 라운드별 메시지 교환 -> 함수 평가 -> 결과 복원 -> 결과 통제
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 참여자·함수·위협 모델 정의 | semi-honest/malicious 명시 |
| 2 | 입력을 share 또는 garbled value로 변환 | 원본 로그 노출 0건 |
| 3 | OT·share 연산 메시지 교환 | round 수, 네트워크 대역폭 |
| 4 | 공동 함수 결과 복원 | 정확도, 실패율, 재시도율 |
| 5 | 결과 공개·감사 | 최소 집단 기준, 질의 횟수 |

> 요약: MPC는 계산보다 네트워크 라운드와 참여자 동기화가 지연을 좌우하므로 프로토콜 선택 시 통신량을 먼저 산정함.

## Ⅳ. 특징

| 구분 | 중앙 결합·TEE | MPC | 판단 포인트 |
|:---|:---|:---|:---|
| 신뢰 경계 | 중개기관 또는 하드웨어 신뢰 | 참여자 간 분산 신뢰 | 중앙 평문 저장 허용 여부 |
| 주요 방식 | DB join, enclave 계산 | secret sharing, garbled circuit, PSI | 함수 유형, 참여자 수 |
| 비용 구조 | 서버 CPU·스토리지 | 통신 라운드·대역폭 | WAN latency, message size |
| 보호 범위 | 저장소·실행환경 통제 | 입력 비공개, 결과 제한 필요 | collusion threshold, output leakage |

> 요약: MPC는 중앙 신뢰를 줄이는 대신 참여자 수와 통신 라운드가 증가할수록 처리 시간이 증가함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 데이터 중앙 수집 | 분산 share 계산 | 원본 반출 금지 계약·규제 |
| 비용/성능 | 단일 DB query | 다자 통신 라운드 | 참여자 2~10개, 배치 처리 적합 |
| 운영/위험 | 중앙 관리자 위험 | 담합·오프라인·결과 추론 위험 | threshold, SLA, output policy |

> 요약: 원본 반출 금지가 우선이고 실시간 응답 요구가 낮은 공동 분석에 MPC를 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 참여자 담합 | t명 이상 share 결합 | t-collusion 모델, key rotation | threshold 위반 테스트 |
| 통신 병목 | WAN 지연·message 폭증 | 라운드 축소 프로토콜, batch | round 수, p95 처리시간 |
| 결과 추론 | 반복 질의·소수 집단 결과 | k 임계값, DP noise, 질의 제한 | privacy budget, 차단 건수 |

> 요약: MPC 리스크는 담합, 통신 병목, 결과 추론이며 위협 모델과 출력 정책으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 보안 | 원본 입력 노출 0건, t-collusion 내성 | 프로토콜 검토, red team |
| 성능 | round 수, 대역폭, p95 처리시간 | 네트워크 trace, 벤치마크 |
| 규제 | 원본 반출 0건, 감사로그 100% | DLP, 접근로그, PIA |

> 요약: MPC 도입 효과는 입력 노출 여부, 통신 성능, 결과 공개 통제, 감사 가능성으로 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 공동 통계, PSI, 모델 학습 등 함수 유형을 분리하고 2-party는 garbled circuit, n-party 합계는 secret sharing 기반으로 선정.
2. semi-honest와 malicious 위협 모델, t-collusion threshold, 참여자 오프라인 재시도 정책을 계약과 기술 명세에 반영.
3. round 수, 대역폭, p95 처리시간, 최소 집단 k, DP epsilon 예산을 PoC 기준으로 측정하고 결과 공개 승인 절차 수립.

**결론 (2줄):**
- 기술사 판단: 원본 반출 금지가 절대 조건이면 MPC, 지연 요구가 ms 단위이면 토큰화·TEE·가명결합을 우선 검토함.
- 향후 방향: PET 결합형 분석은 MPC+DP+연합학습 구조로 발전하며, 프로토콜 성능과 출력 거버넌스가 채점 핵심임.
