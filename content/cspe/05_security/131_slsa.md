## 미리 알고가기

- SLSA는 소프트웨어 산출물이 어떤 소스와 어떤 빌드 절차에서 나왔는지 신뢰 수준을 단계별로 높여 가는 공급망 보안 틀임
- Provenance는 어떤 소스가 어떤 빌드 환경을 거쳐 산출물이 되었는지 설명하는 출처 증빙 정보임
- Hermetic Build는 빌드 중 외부 네트워크나 임의 의존성에 흔들리지 않도록 통제된 환경에서 수행하는 빌드임

## Ⅰ. 개요

- **정의/개념**: SLSA는 소스, 빌드, 산출물 출처 증빙을 단계별로 강화해 위변조와 불신 빌드 경로를 줄이는 공급망 보안 프레임워크임
- **배경/필요성**: 빌드 서버와 의존성 경로가 먼저 침해되는 사고가 늘고 있음. 누가 무엇을 어떻게 빌드했는지 증명해야 함

## Ⅱ. 특징

- 보안 통제를 한 번에 강제하지 않고 성숙도 단계로 올리는 구조임
- 소스 무결성과 빌드 무결성과 산출물 출처 증빙을 함께 다룸
- 수작업 기록보다 자동 생성된 증빙을 중시함
- 높은 단계로 갈수록 빌드 환경 통제가 강해져 도입 범위와 비용을 함께 봐야 함

## Ⅲ. 종류 및 비교

| 수준 | 핵심 초점 | 운영 의미 |
|:---|:---|:---|
| Level 1 | 출처 증빙 생성 시작 | 어떤 빌드가 어떤 산출물을 만들었는지 기록함 |
| Level 2 | 버전 관리된 소스와 신뢰된 빌드 서비스 | 사람이 임의로 바꾼 빌드를 줄임 |
| Level 3 | 더 강한 빌드 격리와 변조 저항 | 빌드 경로 오염 가능성을 낮춤 |
| Level 4 | 재현 가능성과 강한 빌드 통제 | 가장 높은 신뢰 수준을 지향함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 소스 저장소 | 변경 이력과 승인 절차를 남겨 소스 무결성을 확보함 |
| 빌드 서비스 | 통제된 환경에서 자동 빌드를 수행함 |
| 출처 증빙 | 소스, 빌드 환경, 산출물 해시를 묶어 기록함 |
| 정책 검증기 | 배포 전에 증빙 존재 여부와 신뢰 조건을 확인함 |
| 산출물 저장소 | 서명된 패키지와 이미지를 보관하고 배포함 |

```text
소스 변경 -> 통제된 빌드 수행 -> 출처 증빙 생성 -> 정책 검증 -> 산출물 배포
```

## Ⅴ. 원리 및 절차 흐름도

```text
코드 커밋 -> 승인된 빌드 서비스 실행 -> 출처 증빙 생성 -> 서명·검증 -> 배포 허용
```

1. **코드 커밋**: 변경된 소스가 버전 관리 저장소에 반영됨
2. **빌드 서비스 실행**: 승인된 파이프라인만 산출물을 생성함
3. **출처 증빙 생성**: 어떤 입력과 환경에서 빌드됐는지 기록함
4. **서명과 검증**: 산출물과 증빙의 무결성을 확인함
5. **배포 허용**: 기준을 통과한 산출물만 운영으로 넘김

## Ⅵ. 실무 적용 및 유의점

1. 릴리스가 잦은 조직은 핵심 서비스부터 출처 증빙을 의무화하고 출처 증빙 생성률과 서명 없는 빌드 비율로 확인함
2. 외부 빌더와 임시 스크립트가 섞이면 승인된 빌드 경로만 남기고 경로 밖 빌드 건수와 검증 실패 산출물 수로 점검함

## Ⅶ. 결론

- SLSA는 좋은 빌드 습관을 권고하는 문서가 아니라 배포 가능한 산출물의 신뢰 조건을 단계별로 끌어올리는 틀이므로 출처 증빙 자동화가 출발점임
