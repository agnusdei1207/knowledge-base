## 미리 알고가기

- 콘텐츠 진위 정보는 디지털 콘텐츠가 어디서 만들어졌고 어떻게 바뀌었는지에 대한 이력 정보임
- Content Credentials는 콘텐츠의 생성·편집 이력을 서명과 함께 담는 C2PA 형식임
- 전자서명은 파일이나 이력이 중간에 바뀌지 않았는지 확인하는 무결성 장치임

## Ⅰ. 개요

- **정의/개념**: C2PA는 이미지, 영상, 오디오, 문서가 어디서 생성되고 어떤 편집을 거쳤는지 서명된 이력으로 묶어 출처와 변경 내역을 검증하는 개방형 표준임
- **배경/필요성**: 딥페이크 탐지만으로는 진짜를 끝까지 증명하기 어려움. 생성, 편집, 배포로 이어지는 신뢰 사슬이 필요함

## Ⅱ. 특징

- 가짜를 잡는 방식보다 원본과 편집 이력을 증명하는 방식에 가까움
- 생성, 편집, 배포 단계의 기록을 전자서명으로 연결해 위변조 흔적을 남김
- 특정 회사 도구에 묶이지 않도록 상호운용을 목표로 함
- 플랫폼이 메타데이터를 지우면 검증 체인이 끊길 수 있어 유통 경로 관리가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | AI 워터마킹 | C2PA |
|:---|:---|:---|
| 주된 목적 | 생성물 여부와 출처 추적 | 생성·편집 이력과 무결성 증명 |
| 담는 정보 | 숨은 신호나 표식 | 서명된 이력과 변경 기록 |
| 장점 | 대량 검출과 억지 효과에 유리함 | 누가 무엇을 바꿨는지 설명하기 쉬움 |
| 약점 | 제거와 재생성에 약할 수 있음 | 메타데이터가 지워지면 검증이 어려워짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원본 콘텐츠 | 이미지, 영상, 음성, 문서 같은 대상 자산임 |
| Content Credentials | 생성자, 도구, 편집 이력을 담은 서명된 정보 묶음임 |
| 서명 주체 | 카메라, 편집 도구, 생성 서비스처럼 이력을 기록하는 주체임 |
| 검증기 | 서명과 이력 연결이 유효한지 확인함 |
| 신뢰 목록 | 어떤 발급자와 키를 믿을지 정하는 기준임 |

```text
콘텐츠 생성 -> 이력 기록과 서명 -> 편집 이력 추가 -> 배포 -> 검증기 확인
```

## Ⅴ. 원리 및 절차 흐름도

```text
생성 시 이력 부여 -> 편집 때 기록 추가 -> 배포 시 함께 전달 -> 검증기에서 서명 확인 -> 진위와 변경 내역 표시
```

1. **생성 시 이력 부여**: 카메라나 생성 도구가 처음 이력을 만듦
2. **편집 기록 추가**: 편집 도구가 변경 내용을 이어 붙임
3. **배포 시 전달**: 콘텐츠와 이력 정보를 함께 유통함
4. **서명 확인**: 검증기가 이력과 서명을 검사함
5. **결과 표시**: 원본 여부와 편집 경로를 사용자에게 보여 줌

## Ⅵ. 실무 적용 및 유의점

1. 언론사와 기업 미디어 조직은 변환과 업로드 과정에서 이력 정보가 지워지지 않게 파이프라인을 맞추고 검증 성공률과 메타데이터 손실률로 점검함
2. 공개 플랫폼 유통 서비스는 C2PA만 믿지 말고 워터마킹과 탐지를 함께 운영하고 C2PA 검증 실패 건수와 보조 검출 적중률로 확인함

## Ⅶ. 결론

- C2PA는 가짜 판별보다 진짜의 이력을 남기는 표준이므로 유통 경로가 그 이력을 보존하게 만드는 운영 설계가 함께 필요함
