## 미리 알고가기

- FIDO2는 비밀번호 없는 공개키 기반 인증 생태계 전체를 가리키고, WebAuthn은 브라우저와 서비스가 그 인증을 쓰게 하는 웹 표준 API임
- 인증자는 보안키나 스마트폰처럼 개인키를 안전하게 보관하는 장치이고, 서버는 공개키만 저장함
- 피싱 저항성이 높은 이유는 개인키가 서버로 전달되지 않고 서비스 도메인에 묶여 서명되기 때문임

## Ⅰ. 개요

- **정의/개념**: FIDO2·WebAuthn은 공개키 암호 방식으로 사용자 단말의 인증자가 챌린지에 서명하고 서버가 공개키로 검증해 비밀번호 없이 또는 강한 2차 인증으로 로그인하게 하는 표준 체계임
- **배경/필요성**: 패스워드 기반 인증은 피싱과 재사용과 서버 측 비밀 저장 문제를 안고 있어, 비밀을 서버가 보관하지 않고도 사용자 신원을 확인할 수 있는 표준이 필요해짐

## Ⅱ. 특징

- 서버는 공개키만 저장하므로 비밀번호 데이터베이스 탈취 위험이 줄어듦
- 도메인 바인딩이 있어 가짜 사이트에서 동일 자격 증명을 재사용하기 어려움
- 플랫폼 인증자와 휴대형 보안키 모두 활용 가능함
- 등록과 복구와 다중 기기 운영 정책을 함께 설계하지 않으면 도입 초기 지원 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 플랫폼 인증자 | 휴대형 인증자 |
|:---|:---|:---|
| 대표 예시 | 스마트폰 지문, 노트북 생체 인증 | USB/NFC 보안키 |
| 장점 | 사용자 경험이 좋고 추가 장비가 필요 없을 수 있음 | 기기 간 이동이 쉽고 관리 분리가 쉬움 |
| 한계 | 기기 교체와 복구 정책이 중요함 | 분실과 재발급 관리가 필요함 |
| 적합 환경 | 일반 사용자 서비스 | 관리자 계정, 고위험 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 인증자 | 개인키를 안전하게 보관하고 서명을 생성함 |
| 클라이언트 | 브라우저나 OS가 인증자와 서버를 중계함 |
| 서비스 서버 | 챌린지를 발급하고 공개키로 서명을 검증함 |
| 자격 증명 관리 | 등록, 분실, 복구, 추가 등록을 운영함 |

```text
등록 요청 -> 챌린지 발급 -> 인증자 키 생성/서명 -> 공개키 저장 -> 이후 로그인 시 서명 검증
```

## Ⅴ. 원리 및 절차 흐름도

```text
사용자 등록 -> 도메인 바인딩 키 생성 -> 공개키 저장 -> 로그인 챌린지 발급 -> 서명 검증 -> 세션 발급
```

1. **사용자 등록**: 서비스가 인증자 등록을 요청함
2. **키 생성**: 인증자가 해당 서비스 도메인에 묶인 키 쌍을 만듦
3. **공개키 저장**: 서버는 공개키와 메타정보만 저장함
4. **로그인 검증**: 서버가 챌린지를 보내고 인증자가 서명함
5. **세션 발급**: 검증 성공 시 로그인 또는 MFA를 완료함

## Ⅵ. 실무 적용 및 유의점

1. 관리자 계정과 중요 업무 시스템은 FIDO2를 피싱 저항 MFA로 먼저 도입하고, 플랫폼 인증자와 휴대형 보안키를 함께 운영한 뒤 피싱 경로 로그인 차단 여부와 예비 인증자 보유율로 확인함
2. 일반 사용자 서비스는 사용자 경험을 위해 플랫폼 인증자부터 도입하되 복구 경로가 약하면 우회가 생기므로 계정 복구 악용 부재와 등록 실패율과 로그인 성공률 균형으로 확인함

## Ⅶ. 결론

- FIDO2·WebAuthn은 비밀번호를 다른 화면으로 옮기는 기술이 아니라 도메인 바인딩된 공개키 서명으로 피싱과 서버 비밀 저장 문제를 함께 줄이는 인증 체계임
