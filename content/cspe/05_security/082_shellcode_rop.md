## 미리 알고가기

- 쉘코드는 공격자가 직접 주입해 실행하려는 기계어 코드이고, ROP는 프로그램 안에 이미 있는 코드 조각을 이어 실행하는 기법임
- ROP는 DEP나 NX처럼 데이터 영역 실행을 막는 방어를 우회하려고 발전한 방식임
- 둘 다 목적은 실행 흐름 탈취지만 필요한 조건과 방어 지점이 다름

## Ⅰ. 개요

- **정의/개념**: 쉘코드는 주입한 악성 기계어를 직접 실행하는 방식이고, ROP는 기존 명령어 조각을 연결하는 코드 재사용 공격임
- **배경/필요성**: 실행 금지 메모리로 단순 코드 주입이 어려워지며 ROP가 대표 우회 수단이 됨

## Ⅱ. 특징

- 쉘코드는 실행 가능 메모리 확보가 중요하고 ROP는 주소 예측과 가젯 조합이 중요함
- ROP는 OS와 라이브러리의 정상 코드 조각을 악용해 탐지가 까다로움
- 정보 유출 취약점이 함께 있으면 ROP 성공 가능성이 커짐
- 방어는 NX만으로 부족하며 CFI, Shadow Stack, CET가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 쉘코드 주입 | ROP |
|:---|:---|:---|
| 실행 대상 | 공격자가 넣은 새 코드 | 프로그램 안의 기존 코드 조각 |
| 주요 전제 | 실행 가능한 메모리 확보 | 가젯 주소와 체인 구성 가능 |
| 대표 우회 대상 | 입력 검증 부재 | DEP/NX, 단순 실행 차단 |
| 기본 대응 | 입력 차단, NX, 코드 주입 방지 | ASLR, CFI, Shadow Stack, CET |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 취약점 진입점 | 오버플로우나 메모리 오염으로 흐름 탈취가 가능해짐 |
| 페이로드 | 쉘코드 바이트열 또는 가젯 주소 체인이 포함됨 |
| 실행 경로 | 복귀 주소나 함수 포인터가 조작되어 비정상 분기가 발생함 |
| 방어 기법 | NX, ASLR, CFI, Shadow Stack, 하드웨어 CET가 포함됨 |

```text
취약점 악용 -> 제어 흐름 탈취 -> 쉘코드 실행 또는 ROP 체인 수행 -> 악성 행위
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약점 확보 -> 오프셋 계산 -> 페이로드 구성 -> 흐름 탈취 -> 쉘코드/ROP 실행
```

1. **취약점 확보**: 오버플로우나 UAF 같은 진입점을 찾음
2. **오프셋 계산**: 어느 위치의 주소를 덮을지 결정함
3. **페이로드 구성**: 쉘코드 바이트열 또는 ROP 가젯 체인을 만듦
4. **흐름 탈취**: 복귀 주소나 포인터를 바꿔 실행 방향을 틀음
5. **방어 검증**: 동일 공격이 NX와 CFI와 ASLR 아래에서 실패하는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 네이티브 바이너리는 ASLR, CFI, Shadow Stack 적용 상태를 함께 점검하고 가젯 체인 재현 여부·보호 옵션 활성화로 확인함
2. 메모리 취약점 수정 뒤에도 정보 유출이 남으면 ROP 우회가 가능하므로 주소 누출 제거·익스플로잇 체인 차단으로 확인함

## Ⅶ. 결론

- 쉘코드와 ROP는 모두 실행 흐름 탈취를 노리지만 방어 지점이 다르므로 코드 주입 방지와 제어 흐름 보호가 함께 필요함
