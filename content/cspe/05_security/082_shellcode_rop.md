## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 쉘코드는 공격자가 주입하는 기계어 코드이며, ROP는 DEP 우회를 위해 기존 코드의 가젯을 재조합하여 임의 실행하는 기법임 |
| **배경/필요성** | DEP가 데이터 영역 실행을 차단하자, 공격자가 코드 영역의 기존 명령어 조각(가젯)을 연결하는 ROP로 우회하여 방어 무력화 위협이 증가함 |
| **출제 의도** | 쉘코드와 ROP의 동작 원리 차이 및 방어 기법(CFI, Shadow Stack)을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 쉘코드   | --> |  가젯    | --> | ROP체인  |
| (Payload)|     | (코드조각)|     | (연결실행)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 쉘코드 | 공격자가 직접 작성한 기계어 코드로, 셸 획득·파일 다운로드 등 악성 행위를 수행함 | 위조된 열쇠 |
| 가젯 | `ret` 명령으로 끝나는 짧은 명령어 시퀀스로, 라이브러리·바이너리 내에 이미 존재함 | 기존 퍼즐 조각 |
| ROP 체인 | 다수의 가젯 주소를 스택에 순서대로 배치하여 원하는 기능을 연쇄 실행하는 구조임 | 퍼즐 조각을 맞춰 완성한 그림 |

> 요약: 쉘코드(직접 주입)와 ROP(기존 코드 재사용)는 목적은 같으나 DEP 우회 여부에서 차이남.

## Ⅲ. 절차
```
+------------+     +------------+
| 취약점발견  | --> | 가젯탐색   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 임의코드   | <-- | ROP체인   |
| 실행       |     | 스택배치   |
+------------+     +------------+
```

1. 취약점 발견: 오버플로우 가능한 버퍼를 식별하고 리턴 주소 오프셋을 계산함
2. 가젯 탐색: ROPgadget·ropper 등 도구로 바이너리 내 사용 가능한 가젯을 수집함
3. ROP 체인 구성: `pop rdi; ret` → `system()` 주소 순으로 스택에 가젯 주소를 배치함
4. 페이로드 전송: 조합된 ROP 체인을 취약 입력 경로로 전달하여 실행 흐름을 탈취함

> 요약: 취약점 식별 → 가젯 수집 → 체인 구성 → 페이로드 전송으로 DEP를 우회함.

## Ⅳ. 문제점
- DEP 단독 방어 한계: 코드 영역의 기존 가젯을 재사용하므로 DEP만으로 차단 불가함
- ASLR 우회 가능성: 정보 누출(Info Leak) 취약점과 결합 시 라이브러리 주소를 추론하여 ASLR을 무력화함
- JOP/COP 변종: Jump-Oriented·Call-Oriented 변종으로 ROP 탐지 규칙을 회피함

## Ⅴ. 개선방안
- (단기) Shadow Stack 적용: 리턴 주소 사본을 별도 영역에 보관하여 변조 시 탐지·차단함
- (중기) CFI 강제 적용: 허용된 제어 흐름 그래프만 실행 가능하게 하여 비정상 분기를 차단함
- (장기) 하드웨어 CET: Intel CET·ARM BTI 등 하드웨어 레벨에서 간접 분기를 검증함

## Ⅵ. 전망
- Intel CET(Control-flow Enforcement Technology)와 ARM BTI가 주요 CPU에 기본 탑재되면서 하드웨어 기반 ROP 방어가 표준화될 전망임
