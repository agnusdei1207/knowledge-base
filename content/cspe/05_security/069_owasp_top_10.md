## 미리 알고가기

- OWASP Top 10은 웹 애플리케이션에서 자주 문제 되는 보안 위험군을 우선순위 있게 정리한 대표 기준임
- 개별 취약점 목록이 아니라 접근통제, 인젝션, 보안 오설정처럼 설계와 구현에서 반복되는 위험 범주를 보여 줌
- 시험과 실무 모두 항목 암기보다 SDLC에서 어떻게 줄일지로 연결해야 의미가 있음

## Ⅰ. 개요

- **정의/개념**: OWASP Top 10은 웹 애플리케이션에서 반복 발생하고 영향이 큰 보안 위험군을 정리한 우선 관리 기준임
- **배경/필요성**: 웹 보안 문제는 종류가 많고 개발 단계에서 누락되기 쉬움. 설계 검토와 테스트 우선순위를 정할 공통 기준이 필요함

## Ⅱ. 특징

- 웹 보안 위험을 이해하기 쉬운 범주로 묶어 조직 공통 언어를 제공함
- 코딩 실수뿐 아니라 인증, 권한, 로깅, 설정, 공급망 관점도 포함함
- 상세 통제 요구사항은 아니므로 ASVS나 보안 코딩 기준으로 구체화해야 함
- Top 10만 따르면 API, 모바일, 클라우드 특화 위험을 놓칠 수 있음

## Ⅲ. 종류 및 비교

| 대표 위험군 | 의미 | 기본 대응 방향 |
|:---|:---|:---|
| 접근통제 결함 | 권한 검증 누락이나 우회로 타 사용자 자원에 접근함 | 서버 측 권한 검증, 기본 거부, 객체 단위 권한 확인 |
| 인젝션·오설정 | 입력과 설정 관리 실패로 명령 주입이나 불필요 노출이 발생함 | 안전한 인터페이스 사용, 입력 분리, 보안 기본값 강제 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 위험 분류 | 주요 웹 보안 위험을 범주 단위로 정리함 |
| 개발 기준 연결 | 보안 코딩, 설계 검토, 테스트 항목으로 전환함 |
| 검증 활동 | SAST, DAST, 코드 리뷰, 침투 테스트와 연결함 |
| 운영 보완 | 로깅, 경보, WAF, 재검증으로 배포 후 위험을 줄임 |

```text
위험군 이해 -> 설계/코딩 기준 반영 -> 테스트 수행 -> 운영 탐지/개선
```

## Ⅴ. 원리 및 절차 흐름도

```text
위험군 선정 -> 보안 요구사항 정의 -> 개발/테스트 반영 -> 배포 전 검증 -> 운영 중 모니터링
```

1. **위험군 선정**: 조직 서비스에 중요한 웹 보안 범주를 우선 식별함
2. **요구사항 정의**: 인증, 권한, 입력 처리, 로깅 기준을 문서화함
3. **개발과 테스트 반영**: 코드 리뷰와 자동 점검과 침투 테스트를 수행함
4. **배포 전 검증**: 고위험 항목 해소 여부를 확인함
5. **운영 중 개선**: 탐지 로그와 사고 결과를 다시 개발 기준에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 신규 웹·API 서비스는 OWASP Top 10을 설계·코딩·테스트 게이트 입력으로 쓰고 고위험 범주 테스트 커버리지로 확인함
2. 운영 서비스는 사고와 취약점 결과를 자체 기준에 반영하고 반복 취약점 감소율·유형별 재발 방지 반영률로 확인함

## Ⅶ. 결론

- OWASP Top 10은 웹 보안 위험 암기 목록이 아니라 개발과 검증의 우선순위를 정해 반복 결함을 줄이는 공통 기준임
