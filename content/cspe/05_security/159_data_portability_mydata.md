## 미리 알고가기

- 전송 요구권은 정보주체가 자신의 개인정보를 다른 사업자나 기관으로 옮겨 달라고 요구할 수 있는 권리임
- 마이데이터는 이렇게 옮겨진 데이터를 바탕으로 맞춤형 서비스를 제공하는 데이터 이동 생태계임
- 기계 판독 가능 형식은 시스템이 자동으로 읽고 처리할 수 있는 구조화된 데이터 형식을 뜻함

## Ⅰ. 개요

- **정의/개념**: 전송 요구권과 마이데이터는 정보주체가 자신의 개인정보를 본인이나 적정 수신자에게 안전하게 옮기고 활용하게 하는 이동형 데이터 활용 체계임
- **배경/필요성**: 데이터가 한 사업자 안에 갇히면 이용자 선택권과 신규 서비스 경쟁이 약해짐. 개인 주도 이동성과 표준 연계 절차가 필요해짐

## Ⅱ. 특징

- 정보주체 요청이 출발점이므로 동의와 본인 확인과 철회 관리가 핵심임
- 문서 전달이 아니라 기계가 읽는 형식과 표준 API로 전송해야 실서비스에 바로 쓸 수 있음
- 송신자와 수신자와 중계 체계가 함께 움직여야 하므로 보안과 책임 경계가 중요함
- 데이터 이동이 쉬워질수록 과다 수집과 권한 남용 위험도 커져 최소 범위 전송 원칙이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 파일 내려받기 | 스크래핑 방식 | 전송 요구권 기반 마이데이터 |
|:---|:---|:---|:---|
| 데이터 형태 | 사람이 읽기 쉬운 문서에 머무르기 쉬움 | 화면 구조에 의존해 일관성이 낮음 | 기계가 바로 읽는 구조화된 형식으로 전달함 |
| 연계 안정성 | 수동 처리 비중이 큼 | 화면 변경에 취약함 | 표준 연계 인터페이스 기반으로 자동화가 쉬움 |
| 권한 통제 | 내려받은 뒤 추적이 약함 | 계정 위임이 과도해질 수 있음 | 범위와 기간을 나눠 권한을 관리할 수 있음 |
| 서비스 확장성 | 후처리 부담이 큼 | 대규모 운영에 불안정함 | 맞춤형 분석과 연계 서비스에 유리함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정보주체 | 어떤 데이터를 어디로 보낼지 결정하고 철회 여부도 통제하는 중심 주체임 |
| 정보전송자 | 기존에 데이터를 보유한 조직으로, 요청 범위에 맞는 데이터를 안전하게 제공하는 주체임 |
| 수신자 | 전송받은 데이터를 목적 범위 안에서 활용해 새로운 서비스를 제공하는 주체임 |
| 동의와 인증 체계 | 본인 확인과 전송 범위와 유효 기간을 묶어 과도한 접근을 막는 통제 장치임 |
| 전송 지원 플랫폼과 로그 | 표준 연계와 감사 추적을 지원해 장애와 분쟁 대응을 쉽게 하는 운영 기반임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 정보주체      | -> | 수신자 요청    | -> | 정보전송자     | -> | 데이터 활용    |
+-------------+    +-------------+    +-------------+    +-------------+
       ^                                                    |
       +------------------ 동의 철회와 로그 관리 ------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 이용자 동의    | -> | 본인 확인      | -> | 데이터 추출    | -> | 안전 전송      | -> | 활용과 철회    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **이용자 동의**: 정보주체가 수신자와 전송 범위와 목적을 지정함
2. **본인 확인**: 송신자와 수신자가 정당한 요청인지 인증 절차로 확인함
3. **데이터 추출**: 요청 범위에 맞는 정보를 구조화된 형식으로 준비함
4. **안전 전송**: 암호화된 통신과 승인된 인터페이스로 데이터를 전달함
5. **활용과 철회**: 수신자는 목적 범위 안에서만 활용하고 철회 요청이 오면 후속 처리를 수행함

## Ⅵ. 실무 적용 및 유의점

1. 금융, 의료, 통신처럼 데이터 형식이 제각각인 영역은 공통 필드 정의와 철회 반영 절차를 먼저 맞추고 전송 성공률과 철회 반영 지연 시간으로 품질을 확인함
2. 대량 전송 API를 운영할 때는 권한 범위를 토큰에 명확히 묶고 비정상 호출 탐지와 재인증 절차를 두며 과다 요청 차단 건수와 인증 실패율로 이상 징후를 살핌

## Ⅶ. 결론

- 전송 요구권과 마이데이터는 데이터를 더 많이 모으는 제도가 아니라 이용자 주도로 안전하게 옮기는 제도이므로 표준 연계와 권한 통제가 함께 갖춰져야 함
