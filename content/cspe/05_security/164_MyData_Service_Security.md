## Ⅰ. 개요
- 정의: 정보주체가 본인의 개인데이터에 대한 통제권을 갖고, 본인이 원하는 제3자(서비스 제공자)에게 데이터를 이동시켜 맞춤형 서비스를 제공받는 체계에 적용되는 보안임.
- 배경/필요성: 개인정보 이동권 보장 의무화, 스크래핑 방식의 보안 취약성 해결, 데이터 개방 및 유통 과정에서의 인증/인가 표준화 필요.
- 출제 의도: 데이터 생태계의 핵심인 마이데이터의 보안 요구사항(API 보안, 인증, 전송 구간 암호화)과 기술적 구현 방안을 평가함.

## Ⅱ. 구성요소
+-------------------+       +-------------------+       +-------------------+
|  정보제공자       | ----> |  마이데이터 사업자| ----> |    정보주체       |
| (금융/공공 기관)  | (API) | (맞춤형 서비스)   | (App/Web) | (개인 사용자)     |
+-------------------+       +-------------------+       +-------------------+

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 통합 인증/인가 | 정보주체의 신원 확인 및 데이터 전송 요구에 대한 동의/인가 (OAuth 2.0 기반) | 통행증 발급 센터 |
| 표준 API | 정보제공자와 사업자 간 데이터를 안전하고 규격화된 방식으로 전송하는 인터페이스 | 규격화된 전용 도로 |
| 전송 보안 | 데이터 이동 구간(TLS) 및 데이터 암호화 보장 | 장갑차 수송 |

> 요약: 정보주체의 동의 하에, 통합 인증을 거쳐 표준 API를 통해 데이터를 안전하게 수집 및 활용함.

## Ⅲ. 절차
+-------------------+   +-------------------+   +-------------------+   +-------------------+
| 1. 전송 요구/동의 |-->| 2. 통합 인증/인가 |-->| 3. 데이터 API 전송|-->| 4. 활용 및 파기   |
+-------------------+   +-------------------+   +-------------------+   +-------------------+

1. 전송 요구/동의: 정보주체가 마이데이터 앱에서 특정 기관의 데이터를 가져오도록 선택하고 정보 제공 동의서 서명
2. 통합 인증/인가: 정보제공자(또는 중계기관)를 통해 정보주체의 본인 인증 수행 및 접근 토큰(Access Token) 발급
3. 데이터 API 전송: 마이데이터 사업자가 발급받은 토큰을 이용해 표준 API로 안전하게 정보제공자에게 데이터를 요청 및 수신
4. 활용 및 파기: 수집된 데이터를 암호화하여 저장·활용하고, 동의 철회 또는 보유 기간 경과 시 복구 불가능하게 파기

> 요약: 정보주체의 동의 및 통합 인증 후, 표준 API를 통해 데이터를 안전하게 전송받아 활용하고 철저히 파기함.

## Ⅳ. 문제점
- API 보안 위협: API 엔드포인트에 대한 접근 통제 우회, 토큰 탈취, 비정상적 과다 호출(DDoS) 공격 위험
- 과도한 동의 유도: 다크 패턴(Dark Pattern)을 통한 포괄적 동의 유도 및 정보주체의 실질적 통제권 상실 우려
- 제3자 유출 위험: 마이데이터 사업자의 보안 인프라 취약 시, 수집된 대량의 개인정보가 해킹으로 유출될 위험
- 스크래핑 혼용: 일부 표준 API가 미지원되는 영역에서 여전히 스크래핑이 사용되어 인증 정보 유출 위험 잔존

## Ⅴ. 개선방안
- 단기: API 게이트웨이 도입으로 트래픽 통제, OAuth 2.0 기반 토큰 생명주기 관리 강화 및 FDS(이상거래탐지) 연동
- 중기: 마이데이터 사업자 대상 정기적 취약점 점검 및 ISMS-P 인증 의무화, 스크래핑 전면 금지 및 API 전환 가속화
- 장기: 동적 동의(Dynamic Consent) 체계 및 블록체인 기반 데이터 이력 관리 시스템 도입으로 투명한 데이터 통제권 보장

## Ⅵ. 전망
- 금융권을 넘어 의료, 통신, 공공 등 전 산업 분야로 마이데이터가 확장되며 크로스 도메인 API 보안 표준이 정립될 것임.
- 제로 트러스트(Zero Trust) 아키텍처 기반의 상호 인증 및 마이크로 인가 체계가 마이데이터 인프라의 기본 요건이 될 전망임.
