## Ⅰ. 개요
- **정의**: 임의 길이 입력을 고정 길이 해시값으로 변환하는 단방향 함수
- **배경/필요성**: 데이터 무결성 검증, 비밀번호 저장, 디지털 서명에서 원본 노출 없이 동일성을 확인할 수단이 필요함
- **비유**: 지문 채취와 같이 원본(사람)을 복원할 수 없지만 동일인 여부를 판별 가능함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해시 함수의 보안 요건 이해 | 역상 저항성·제2역상 저항성·충돌 저항성 | 암호화와 해싱의 차이(단방향 vs 양방향) |

> 요약: 해시 함수는 단방향성·충돌 저항성을 기반으로 무결성과 인증을 보장하는 함수임

## Ⅱ. 구성요소
```text
[입력 메시지] --> [패딩] --> [블록 분할] --> [압축 함수 반복] --> [해시값]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 역상 저항성 | 해시값으로부터 원본 입력을 계산하는 것이 불가능한 성질 | 지문에서 사람 복원 불가 |
| 제2역상 저항성 | 주어진 입력과 동일 해시값을 갖는 다른 입력을 찾기 어려운 성질 | 같은 지문의 타인 찾기 불가 |
| 충돌 저항성 | 동일 해시값을 갖는 임의의 두 입력을 찾기 어려운 성질 | 지문 중복 불가 |
| 눈사태 효과 | 입력 1비트 변경 시 해시값의 약 50%가 변하는 성질 | 나비효과 |

> 요약: 3가지 저항성과 눈사태 효과가 암호학적 해시 함수의 필수 요건임

## Ⅲ. 절차
```text
입력 수신 --> 전처리(패딩) --> 압축 함수 반복 --> 최종 해시값 출력
```
- 1단계: 임의 길이 메시지를 수신하여 블록 크기에 맞게 패딩을 추가함
- 2단계: 초기 해시값(IV)을 설정하고 메시지를 고정 크기 블록으로 분할함
- 3단계: 각 블록에 대해 압축 함수를 순차 적용하여 중간 해시값을 갱신함
- 4단계: 마지막 블록 처리 후 최종 고정 길이 해시값을 출력함

> 요약: 패딩 → 블록 분할 → 압축 함수 반복 → 고정 길이 출력의 Merkle-Damgard 구조임

## Ⅳ. 문제점
- MD5·SHA-1 취약: 충돌 공격이 실증되어 보안 용도로 사용이 불가함
- 레인보우 테이블: 비밀번호 해싱 시 솔트 없이 사용하면 사전 계산 공격에 취약함
- 길이 확장 공격: Merkle-Damgard 구조에서 해시값만으로 추가 데이터를 덧붙인 유효 해시를 생성할 수 있음

> 요약: 구형 알고리즘 취약, 솔트 미적용 시 사전공격, 구조적 길이 확장 공격이 주요 위험임

## Ⅴ. 개선방안
1. 단기: SHA-256 이상 또는 SHA-3 계열로 알고리즘을 전환함
2. 중기: 비밀번호 저장 시 bcrypt·Argon2 등 솔트+반복 해싱을 적용함
3. 장기: HMAC·SHA-3(스펀지 구조)를 도입하여 길이 확장 공격을 원천 차단함

> 요약: 알고리즘 전환 → 솔트 해싱 → 구조적 방어로 단계적으로 위험을 제거함

## Ⅵ. 전망
- 발전 방향: SHA-3(Keccak)의 스펀지 구조가 차세대 표준으로 확산되는 추세임
- 기술사적 판단: 블록체인·디지털 서명·무결성 검증 등 활용 범위가 지속 확대됨
- 기술사 제언: 양자 컴퓨터 대비 해시 출력 길이 확대(256비트 이상)와 PQC 서명 연계가 필요함
