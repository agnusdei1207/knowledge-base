## 미리 알고가기

- 가명처리는 추가 정보 없이는 특정 개인을 바로 알아보기 어렵게 바꾸는 처리 방식임
- 익명처리는 추가 정보가 있어도 개인을 알아볼 수 없게 만드는 것을 목표로 함
- 마스킹은 일부 값을 가리거나 치환해 노출을 줄이는 단순 비식별 기법임

## Ⅰ. 개요

- **정의/개념**: 비식별 처리는 개인정보를 분석, 테스트, 공유에 활용할 때 개인을 바로 알아보거나 다시 연결하기 어렵도록 변환하는 기법과 관리 절차임
- **배경/필요성**: 원본 데이터를 그대로 쓰면 활용은 쉽지만 유출과 재식별 위험이 커짐. 너무 강하게 숨기면 활용 가치가 떨어져 목적별 균형이 필요함

## Ⅱ. 특징

- 기술 하나로 끝나는 작업이 아니라 목적, 데이터 특성, 재식별 가능성을 함께 봐야 함
- 가명처리는 활용성을 남기기 좋지만 추가 정보 분리 보관이 필수임
- 익명처리는 보호 수준이 높지만 통계 품질과 세밀한 분석력이 떨어질 수 있음
- 마스킹은 운영 화면 노출을 줄이는 데 유용하지만 단독으로는 재식별 위험을 충분히 막지 못할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 가명처리 | 익명처리 | 마스킹 |
|:---|:---|:---|:---|
| 재식별 가능성 | 추가 정보가 있으면 다시 연결될 수 있음 | 합리적인 수단으로 재식별이 어려워야 함 | 원본이 다른 곳에 남아 있으면 쉽게 복원될 수 있음 |
| 활용 목적 | 연구, 분석, 결합 활용에 적합함 | 공개 통계나 외부 제공에 적합함 | 화면 표시나 테스트 데이터 보호에 적합함 |
| 장점 | 데이터 유용성을 비교적 잘 유지함 | 보호 수준이 가장 높음 | 적용이 빠르고 운영 부담이 낮음 |
| 주의점 | 가명 키 분리와 접근 통제가 중요함 | 과도한 일반화로 정보 가치가 떨어질 수 있음 | 단독 적용만으로는 안전하다고 보기 어려움 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 직접 식별자 | 이름, 주민등록번호, 연락처처럼 개인을 바로 식별하게 하는 정보임 |
| 준식별 정보 | 생년월일, 지역, 직업처럼 다른 정보와 결합되면 개인을 좁힐 수 있는 정보임 |
| 변환 규칙 | 삭제, 일반화, 범주화, 치환 같은 기법을 어떤 필드에 적용할지 정한 기준임 |
| 추가 정보 분리 저장 | 가명 키나 원본 매핑 정보를 분리 보관해 무단 재연결을 막는 장치임 |
| 재식별 위험 평가 | 변환 뒤에도 다시 개인을 찾을 가능성이 남는지 확인하는 검증 단계임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 원본 데이터    | -> | 식별자 분류    | -> | 변환 적용      | -> | 위험 재평가    |
+-------------+    +-------------+    +-------------+    +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 목적 정의      | -> | 필드 분류      | -> | 기법 선택      | -> | 변환 수행      | -> | 위험 검증      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **목적 정의**: 분석, 테스트, 외부 제공 중 어떤 목적인지 먼저 정함
2. **필드 분류**: 직접 식별자와 준식별 정보와 민감 정보를 나눔
3. **기법 선택**: 가명처리, 익명처리, 마스킹 중 목적에 맞는 방식을 고름
4. **변환 수행**: 삭제, 치환, 일반화, 범주화 같은 규칙을 실제 데이터에 적용함
5. **위험 검증**: 재식별 가능성과 데이터 활용 가능성을 함께 확인함

## Ⅵ. 실무 적용 및 유의점

1. 분석용 데이터셋은 활용 목적에 맞는 비식별 수준을 정하고 재식별 시험 결과와 분석 정확도 저하율을 함께 보며 방식이 과한지 부족한지 판단함
2. 가명 키를 운영하는 환경은 원본과 분리된 저장소와 별도 권한 체계를 두고 가명 키 접근 건수와 비인가 접근 시도 수로 통제 수준을 확인함

## Ⅶ. 결론

- 비식별 처리는 값을 가리는 작업이 아니라 재식별 위험과 활용 가치를 함께 조정하는 작업이므로 목적과 통제 수준을 같이 설계해야 함
