## Ⅰ. 개요
- **정의**: 서버가 공격자가 지정한 내부/외부 URL로 요청을 대신 보내도록 유도하는 공격
- **배경/필요성**: 클라우드 메타데이터 API, 내부 마이크로서비스 등 서버만 접근 가능한 자원이 SSRF로 노출됨
- **비유**: 회사 직원에게 내부 금고 열쇠를 가져오라고 속여 외부인이 이용하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 서버측 취약점 이해 | 클라우드 메타데이터 탈취 시나리오 | XXE와 SSRF 연계 가능성 언급 |

> 요약: SSRF는 서버의 요청 권한을 악용하여 내부 네트워크 자원에 무단 접근하는 공격임

## Ⅱ. 구성요소
```text
공격자 --URL 파라미터--> 취약 서버 --내부 요청--> 내부 서비스/메타데이터
                              |
                              v
                        응답을 공격자에게 반환
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| URL 입력점 | 서버가 사용자 입력 URL을 fetch하는 기능(이미지 로드, webhook 등) | 심부름 요청 창구 |
| 내부 네트워크 | 방화벽 뒤에 있어 외부에서 접근 불가한 서비스 영역 | 보안 구역 내부 |
| 클라우드 메타데이터 | `169.254.169.254`로 접근하는 인스턴스 자격증명 API | 금고 속 열쇠 |

> 요약: URL 입력점을 통해 서버가 내부 네트워크와 클라우드 메타데이터에 접근하는 것이 핵심임

## Ⅲ. 절차
```text
URL 조작 --> 서버 요청 발생 --> 내부 리소스 접근 --> 응답 데이터 유출
```
- 1단계: URL 조작 — 공격자가 파라미터에 내부 IP(`127.0.0.1`, `169.254.169.254`)를 삽입함
- 2단계: 서버 요청 — 서버가 입력된 URL로 HTTP 요청을 수행함
- 3단계: 내부 접근 — 방화벽 내부 서비스나 클라우드 메타데이터 API에 접근함
- 4단계: 데이터 유출 — IAM 자격증명, DB 연결 정보 등이 응답으로 반환되어 탈취됨

> 요약: URL 조작-서버 요청-내부 접근-유출의 4단계로 내부 자원이 외부에 노출됨

## Ⅳ. 문제점
- 자격증명 탈취: 클라우드 메타데이터에서 IAM 임시 자격증명이 유출되면 전체 계정 장악 가능
- 내부 스캔: SSRF를 통해 내부 포트 스캐닝과 서비스 탐색이 가능함
- 필터 우회: IP 주소 인코딩(8진수, 16진수), DNS 리바인딩 등으로 차단 로직을 우회함

> 요약: 자격증명 탈취, 내부 스캐닝, 필터 우회가 SSRF의 핵심 위협임

## Ⅴ. 개선방안
1. 단기: 허용 URL 화이트리스트 방식으로 서버의 외부 요청 대상을 제한함
2. 중기: 클라우드 메타데이터 API에 IMDSv2(토큰 기반) 적용으로 SSRF 직접 접근을 차단함
3. 장기: 네트워크 수준에서 서버의 아웃바운드 트래픽을 세그먼트별로 제한하는 이그레스 정책 수립

> 요약: URL 화이트리스트, IMDSv2, 이그레스 제한으로 SSRF를 다계층 방어함

## Ⅵ. 전망
- 발전 방향: 서버리스, 마이크로서비스 환경에서 서비스 간 호출이 증가하며 SSRF 공격 표면이 확대됨
- 기술사적 판단: IMDSv2 의무화, 네트워크 정책 자동화 등 클라우드 네이티브 방어가 표준화될 전망
- 기술사 제언: 서버가 외부 URL을 fetch하는 모든 기능에 대해 입력 검증과 이그레스 제한을 설계 단계에서 적용해야 함
