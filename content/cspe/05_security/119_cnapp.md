# 📖 【암기용】 개념 완전 이해

> 목적: CNAPP을 처음 보는 사람도 CSPM, CWPP, CIEM이 왜 통합되는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: CNAPP은 클라우드 네이티브 애플리케이션의 형상, 워크로드, 권한, 개발 파이프라인 위험을 통합 관리하는 보안 플랫폼임
- **왜 필요한가**: 클라우드 사고는 설정 오류, 취약 이미지, 과도 권한, 런타임 침해가 연결되어 발생한다. 개별 도구가 따로 경고하면 실제 공격 경로와 우선순위를 판단하기 어렵다.
- **핵심 직관**: 건물 도면 점검, 입주자 행동 감시, 출입권한 관리, 공사장 안전검사를 하나의 상황판에서 연결해 보는 통합 관제임

## 깊이 이해
- **배경·문제의식**: CSPM은 설정 오류, CWPP는 워크로드 런타임, CIEM은 권한 과다를 본다. 그러나 공개 버킷, 취약 컨테이너, 관리자 권한, 인터넷 노출이 동시에 존재할 때 우선순위는 연결 분석으로 판단해야 한다.
- **작동 원리**: CNAPP은 클라우드 자산, IaC, 이미지, Kubernetes, IAM, 네트워크 노출, 런타임 이벤트를 수집한다. 위험 그래프를 만들어 "인터넷 노출 VM에 Critical CVE와 과도 권한이 있음" 같은 공격 경로를 제시하고 조치 순서를 정한다.
- **비유**: 병원에서 혈압, 혈당, 엑스레이, 처방 기록을 따로 보지 않고 환자 1명의 위험도를 종합해 응급실 우선순위를 정하는 방식임
- **구체 예시**: 인터넷 공개 보안그룹, Log4Shell 취약 컨테이너, S3 쓰기 권한 Role이 연결된 워크로드를 Critical로 산정하고 24시간 이내 패치·권한 제거·노출 차단을 요구함
- **흔한 오해·주의점**: CNAPP은 단순 번들 제품이 아니다. 핵심은 CSPM, CWPP, CIEM, IaC 스캔 결과를 자산·권한·노출 관계로 연결해 조치 우선순위를 줄이는 것임

## 연결 개념
- CSPM — 클라우드 형상 오류 탐지
- CWPP — 워크로드 취약점과 런타임 보호
- CIEM — 클라우드 권한 과다와 권한 경로 분석

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CNAPP은 기능 목록이 아니라 개발부터 운영까지 클라우드 네이티브 위험을 상관 분석해 우선순위와 조치를 제공하는 통합 플랫폼으로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CNAPP(Cloud Native Application Protection Platform)은 CSPM, CWPP, CIEM, IaC 보안을 통합해 클라우드 네이티브 애플리케이션 위험을 관리하는 플랫폼이다.
> 2. **가치**: 설정 오류, 취약점, 과도 권한, 런타임 이벤트를 공격 경로로 연결해 Critical 조치 대상을 줄인다.
> 3. **판단 포인트**: 위험 그래프, DevSecOps 연계, 런타임 보호, 권한 분석, 조치 SLA를 함께 제시해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 네이티브 통합 보안 이해 확인 | CSPM, CWPP, CIEM, IaC, KSPM 통합 | 개별 도구 나열로 끝냄 |
| 위험 우선순위 판단 확인 | 공격 경로, 노출도, 취약점, 권한 관계 | 경고 수 감소만 주장하고 근거 지표 부재 |
| DevSecOps 적용 역량 확인 | 코드, 빌드, 배포, 런타임 전 단계 통제 | 운영 단계 탐지만 쓰고 파이프라인 통제 누락 |

> 요약: CNAPP 답안은 클라우드 위험을 단일 그래프로 연결해 조치 우선순위를 산정하는 구조를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 클라우드 네이티브 보안 통합
- 배경: 클라우드 네이티브 환경은 IaC, 컨테이너, Kubernetes, IAM, 멀티클라우드가 결합되어 단일 도구로 공격 경로를 판단하기 어렵다.
- 필요성: CNAPP은 CSPM, CWPP, CIEM, IaC 스캔 결과를 연결해 공격 경로와 조치 우선순위를 위험도 기준으로 산정해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Code/IaC -> Image/Registry -> Cloud Config -> Workload Runtime -> Identity Graph
      +-> CNAPP Data Lake/Risk Graph
Risk Graph -> Prioritization -> Ticket/Policy/Block -> Evidence
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CSPM | 클라우드 설정 오류와 규정 준수 점검 | 공개 스토리지, 로그, 암호화, 보안그룹 |
| CWPP | 이미지 취약점과 런타임 위협 탐지 | 컨테이너, VM, 서버리스 보호 |
| CIEM | IAM 권한 과다와 권한 경로 분석 | 미사용 권한, 특권 Role, Cross Account |
| IaC/KSPM | Terraform, Kubernetes 매니페스트 정책 검사 | 배포 전 차단과 정책 드리프트 확인 |
| Risk Graph | 자산, 취약점, 권한, 노출 관계 분석 | 공격 경로 기반 우선순위 산정 |

> 요약: CNAPP은 형상, 워크로드, 권한, 코드 위험을 위험 그래프로 연결해 단일 조치 흐름을 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산/코드/런타임 데이터 수집 -> 위험 정규화 -> 관계 그래프 생성
-> 공격 경로 분석 -> 우선순위 산정 -> 티켓/자동조치
-> 정책 개선/감사 증적
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 클라우드 계정, IaC, 이미지, K8s, IAM 데이터 수집 | 계정·클러스터 커버리지 95% 이상 |
| 2 | 취약점, 설정 오류, 권한, 노출 이벤트 정규화 | 중복 경고 30% 이상 제거 |
| 3 | 자산과 권한 관계 기반 위험 그래프 생성 | 인터넷 노출+Critical CVE+특권 조합 탐지 |
| 4 | 위험도와 업무 중요도로 조치 우선순위 산정 | Critical 24시간, High 7일 이내 |
| 5 | 티켓, 정책 차단, 자동 수정, 증적 보존 | 조치 완료율 95% 이상 |

> 요약: CNAPP은 개별 경고를 자산 관계로 묶어 공격 가능성과 업무 영향 기준으로 우선순위를 산정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CSPM, CWPP, CIEM, IaC 스캔을 단일 자산 모델로 통합하고 계정·클러스터·Registry·CI/CD 커버리지 95% 이상을 확보함
2. 인터넷 노출, Critical CVE, 특권 Role, 민감데이터 접근을 결합한 위험 그래프 규칙을 만들고 Critical 24시간 조치 SLA를 적용함
3. GitHub Actions, GitLab CI, Jira, ServiceNow, SIEM/SOAR와 연계해 배포 전 차단과 런타임 격리를 같은 티켓 흐름으로 관리함

**결론 (2줄):**
- 기술사 판단: 단일 클라우드 소규모 환경은 CSPM부터 시작하고, 멀티클라우드·Kubernetes·DevOps가 결합되면 CNAPP 통합이 필요함
- 향후 방향: CNAPP은 DSPM, ASPM, AI 보안 위험까지 통합해 클라우드 자산 위험 그래프 중심으로 발전함
