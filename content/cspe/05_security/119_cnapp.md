## 미리 알고가기

- 클라우드 네이티브는 컨테이너, 쿠버네티스, 마이크로서비스, IaC를 중심으로 빠르게 배포하는 운영 방식을 말함
- IaC는 인프라 설정을 코드로 관리하는 방식이며 대표 예로 Terraform이 있음
- 위험 맥락은 취약점, 권한, 노출 상태를 따로 보지 않고 한 흐름으로 묶어 본 정보를 말함

## Ⅰ. 개요

- **정의/개념**: CNAPP는 CSPM, CWPP, CIEM, IaC 점검 같은 클라우드 보안 기능을 한 플랫폼에서 묶어 코드부터 런타임까지의 위험을 연결해서 보는 통합 보호 체계임
- **배경/필요성**: 설정 오류, 과도 권한, 취약 워크로드가 각각 다른 도구에 흩어져 있으면 실제 공격 경로를 읽기 어려워 통합된 상관 분석이 필요해짐

## Ⅱ. 특징

- 배포 전 IaC와 이미지 점검부터 배포 후 런타임 감시까지 한 흐름으로 다룸
- 설정, 권한, 취약점, 네트워크 노출을 묶어 실제 공격 가능성이 높은 경로를 먼저 보여줌
- 포인트 솔루션보다 운영 화면과 조치 흐름을 단순화하기 쉬움
- 데이터 품질이 낮으면 상관 분석 결과도 흔들리므로 자산 관계 정보가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 개별 포인트 솔루션 운영 | CNAPP |
|:---|:---|:---|
| 가시성 | 설정, 권한, 워크로드가 분리되어 보임 | 위험을 한 화면에서 연결해 봄 |
| 우선순위화 | 도구별 경보가 따로 쌓임 | 실제 공격 경로 기준으로 묶어 정렬함 |
| 조치 연계 | 팀 간 넘김이 잦음 | 개발, 플랫폼, 보안팀 흐름을 묶기 쉬움 |
| 적합 환경 | 범위가 작고 구조가 단순한 환경 | 멀티 클라우드와 컨테이너 중심 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IaC·코드 점검 | 배포 전 잘못된 설정과 노출 위험을 찾음 |
| CSPM | 운영 중 계정과 리소스의 오설정을 계속 점검함 |
| CIEM | 사용자와 서비스 계정의 과도 권한을 분석함 |
| CWPP | 워크로드 취약점과 런타임 위협을 감시함 |
| 그래프 분석 | 자산, 권한, 노출, 취약점 관계를 연결해 공격 경로를 계산함 |

```text
코드/IaC -> 배포 -> 운영 설정 점검
                 -> 권한 분석
                 -> 워크로드 감시
                 -> 위험 상관 분석/우선순위화
```

## Ⅴ. 원리 및 절차 흐름도

```text
코드와 이미지 점검 -> 클라우드 설정 수집 -> 권한과 워크로드 정보 결합 -> 공격 경로 계산 -> 우선순위 조치 -> 재평가
```

1. **사전 점검**: IaC와 이미지에서 설정 오류와 취약 패키지를 찾음
2. **운영 수집**: 배포된 리소스의 설정과 권한과 런타임 정보를 모음
3. **관계 결합**: 어떤 자산이 어떤 권한과 노출을 가지는지 연결함
4. **우선순위화**: 실제 침해로 이어질 수 있는 조합을 먼저 올림
5. **조치와 재평가**: 수정 후 동일 경로가 끊겼는지 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 멀티 클라우드와 쿠버네티스 환경은 오설정 하나보다 노출 자산과 과도 권한과 취약 워크로드가 이어진 경로를 먼저 끊고 고위험 공격 경로 수와 조치 완료 시간으로 확인함
2. 도구를 통합해도 자산 태그와 서비스 관계가 틀리면 우선순위가 흔들리므로 애플리케이션 소유 정보부터 맞추고 잘못 묶인 경보 비율과 장기 미조치 건수로 점검함

## Ⅶ. 결론

- CNAPP는 클라우드 보안 도구를 단순히 한데 모으는 제품이 아니라 코드·설정·권한·워크로드를 공격 경로로 연결해 우선순위를 다시 세우는 운영 방식임
