## 미리 알고가기

- KEM: 공개키로 공유 비밀을 캡슐화하는 키 교환 방식임
- DEM: 대칭키로 실제 데이터를 암호화하는 데이터 암호화 방식임
- 세션키: 한 연결이나 세션에서 사용하는 임시 대칭키임
- PFS: 장기 개인키가 유출되어도 과거 세션키 복구를 어렵게 하는 성질임
- AEAD: 암호문과 인증 태그를 함께 생성하는 대칭 암호 모드임

## Ⅰ. 개요

- **정의/개념**: 하이브리드 암호는 공개키 방식으로 세션키를 합의하고 대칭키 방식으로 데이터를 암호화하는 구조임
- **배경/필요성**: 공개 환경의 키 분배 문제와 대용량 데이터 암호화 비용을 한 프로토콜 안에서 분리해 처리해야 함

## Ⅱ. 특징

- 공개키 연산은 세션키 합의나 캡슐화 구간에 제한함
- 데이터 본문은 대칭 암호와 AEAD로 처리함
- 인증서 검증이 빠지면 세션키 합의 전에 상대 신원을 확인할 수 없음
- PFS는 정적 RSA 키 교환보다 임시 DH 계열에서 확보하기 쉬움

## Ⅲ. 종류 및 비교

| 구분 | RSA 키 전송형 | DH/ECDHE 합의형 | PQC 하이브리드형 |
|:---|:---|:---|:---|
| 키 생성 | 클라이언트가 세션키 재료를 암호화 | 양측 임시 키로 공유 비밀 계산 | 기존 KEX와 PQC KEM 결과 결합 |
| PFS | 서버 개인키 유출 시 과거 세션 위험 | 임시 키 폐기 시 과거 세션 보호 | 전환기 알고리즘 위험 분산 |
| 대표 환경 | 레거시 TLS | TLS 1.2/1.3 ECDHE | PQC 전환기 TLS 실험·도입 |
| 적용 판단 | 신규 적용 지양 | 일반 인터넷 서비스 | 장기 기밀성 요구 구간 |

> 요약: 하이브리드 암호의 비교 기준은 결합했다는 사실이 아니라 세션키 생성 절차와 PFS 여부임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 공개키 알고리즘 | 세션키 재료 합의 또는 캡슐화 |
| 인증서·서명 | 상대 공개키와 서버 신원 검증 |
| 세션키 | 실제 데이터 암호화에 사용되는 임시 키 |
| 대칭 암호 | 애플리케이션 데이터 암호화 |
| MAC·AEAD 태그 | 암호문 변조 여부 검증 |

```text
인증서 검증 -> 키 교환/KEM -> 세션키 도출 -> 대칭 암호화 -> 태그 검증
```

## Ⅴ. 원리 및 절차 흐름도

1. **인증서 확인**: 서버 공개키와 인증서 체인을 검증함
2. **키 교환**: ECDHE 또는 KEM으로 공유 비밀을 생성함
3. **키 도출**: KDF로 암호화 키와 인증 키를 분리함
4. **데이터 보호**: AEAD로 본문 암호화와 태그 생성을 수행함
5. **세션 종료**: 임시 키와 세션 상태를 폐기함

## Ⅵ. 실무 적용 및 유의점

- TLS 1.3은 정적 RSA 키 교환을 제거하고 임시 DH 기반 절차를 사용함
- PGP와 S/MIME은 메시지 본문은 대칭키로, 세션키는 공개키로 보호함
- PQC 전환기에는 기존 ECDHE와 ML-KEM을 함께 써 상호 운용성을 검증함
- 인증서 검증 실패를 무시하면 하이브리드 구조도 중간자 공격을 막지 못함
- 암호 스위트 선택은 키 교환, 인증, AEAD 모드를 함께 봐야 함

## Ⅶ. 결론

- 하이브리드 암호는 공개키와 대칭키의 역할을 분리해 통신 채널을 구성하는 방식임
- 답안에서는 “장점 결합”보다 인증서 검증, 키 교환, 세션키 도출, 데이터 보호 절차를 써야 함

## 작성 근거(검토용)

- 기존 문서의 비유와 과장 표현을 제거하고 KEM-DEM 절차 중심으로 재구성함
- 선택 기준을 속도 표현이 아니라 PFS, 인증서 검증, 세션키 생성 방식으로 좁힘
- TLS와 PQC 하이브리드를 같은 흐름에서 설명해 003, 014, 019번 연결성을 맞춤
