## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | FIDO2 기반 공개키 자격증명을 클라우드에 동기화하여, 비밀번호 입력 없이 생체·PIN만으로 인증하는 차세대 자격증명임 |
| **배경/필요성** | FIDO2 보안키의 기기 종속 문제를 해결하고, 패스워드 완전 제거를 위해 플랫폼 간 동기화 가능한 자격증명이 필요함 |
| **출제 의도** | 패스키의 동기화 메커니즘과 기존 FIDO2 보안키와의 차이를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 플랫폼   | --> | 클라우드  | --> | 서비스   |
| 인증자   |     | 동기화   |     | (RP)     |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 플랫폼 인증자 | 스마트폰·PC의 TPM·Secure Enclave에서 개인키를 보호하고 생체 인증을 수행함 | 스마트폰 내장 금고 |
| 클라우드 동기화 | iCloud Keychain·Google Password Manager를 통해 패스키를 디바이스 간 동기화함 | 클라우드 백업 금고 |
| 크로스 디바이스 | 하이브리드 전송(caBLE/BLE)으로 스마트폰이 PC 브라우저의 인증을 대리 수행함 | 스마트폰으로 PC 로그인 |

> 요약: 플랫폼 인증자(생체) + 클라우드 동기화로 기기 종속 없는 패스워드리스 인증을 구현함.

## Ⅲ. 절차
```
+------------+     +------------+
| 패스키등록  | --> | 클라우드   |
| (생체+키생성)|    | 동기화     |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 로그인완료  | <-- | 생체인증  |
|            |     | 서명전송   |
+------------+     +------------+
```

1. 패스키 등록: 서비스에서 패스키 생성을 요청하면 디바이스가 키쌍을 생성하고 공개키를 서버에 등록함
2. 클라우드 동기화: 개인키가 E2E 암호화되어 iCloud/Google 계정에 동기화됨
3. 인증 요청: 다른 디바이스에서 로그인 시 동기화된 패스키로 챌린지에 서명함
4. 서명 검증: 서버가 공개키로 서명을 검증하고, 생체 확인이 완료되면 세션을 발급함

> 요약: 등록(키생성) → 동기화 → 인증(생체+서명) → 검증으로 어떤 기기에서든 패스워드 없이 로그인함.

## Ⅳ. 문제점
- 클라우드 계정 탈취: Apple/Google 계정이 탈취되면 패스키도 함께 유출될 위험이 있음
- 에코시스템 종속: Apple↔Google↔MS 간 패스키 호환·이관이 아직 완전하지 않음
- 엔터프라이즈 관리: 조직 내 패스키 배포·폐기·감사 정책이 미성숙함

## Ⅴ. 개선방안
- (단기) 계정 보호 강화: 클라우드 계정 자체에 하드웨어 보안키 MFA를 적용함
- (중기) FIDO Alliance CXP: Cross-Platform Credential Exchange 표준으로 벤더 간 패스키 이관을 지원함
- (장기) 엔터프라이즈 MDM 연동: MDM/EMM과 패스키 생명주기를 통합하여 조직 차원의 관리를 자동화함

## Ⅵ. 전망
- 2027년까지 주요 웹 서비스의 패스워드 로그인이 패스키로 대체되며, CXP 표준으로 벤더 종속 없는 범용 패스워드리스 생태계가 완성될 전망임
