## 미리 알고가기

- 패스키는 FIDO2 기반 자격 증명을 사용자가 쉽게 쓰도록 기기와 클라우드 동기화까지 포함해 제공하는 형태의 인증 수단임
- 서비스 입장에서는 공개키 기반 인증이고, 사용자 입장에서는 비밀번호 대신 생체나 PIN으로 로그인하는 경험에 가까움
- 패스키는 보안키와 경쟁하기보다 일반 사용자 확산을 쉽게 만든 운영 방식으로 이해하는 편이 맞음

## Ⅰ. 개요

- **정의/개념**: 패스키는 FIDO2 공개키 자격 증명을 플랫폼 인증자에 저장하고 동기화해 여러 기기에서 비밀번호 없이 로그인하게 하는 방식임
- **배경/필요성**: FIDO2는 강하지만 전용 보안키와 기기 종속성이 확산 장벽이 됨. 쉬운 등록·복구·다중 기기 경험이 필요함

## Ⅱ. 특징

- 사용자는 비밀번호 대신 생체나 PIN 확인만 하므로 편의성이 높음
- 공개키 기반이라 서버에 비밀번호 비밀값을 저장하지 않음
- 동기화와 크로스 디바이스 지원으로 다중 기기 사용이 쉬움
- 클라우드 계정 보호와 복구 정책이 약하면 편의성이 우회 경로가 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 패스키 | 전통적 보안키 중심 FIDO |
|:---|:---|:---|
| 사용자 경험 | 플랫폼 내장 인증과 동기화로 접근이 쉬움 | 별도 장치를 준비해야 할 수 있음 |
| 확산성 | 일반 소비자 서비스에 적합 | 고위험 계정에 특히 적합 |
| 강점 | 기기 간 사용과 복구 편의성이 높음 | 물리적 분리와 관리 통제가 쉬움 |
| 유의점 | 클라우드 계정 보안과 동기화 정책 중요 | 분실과 예비 키 관리 중요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 플랫폼 인증자 | 개인키를 안전하게 저장하고 생체나 PIN으로 사용을 승인함 |
| 동기화 계정 | 여러 기기 간 자격 증명 사용 편의를 제공함 |
| 서비스 서버 | 공개키를 저장하고 로그인 시 서명을 검증함 |
| 복구와 관리 정책 | 기기 분실과 계정 복구와 조직 정책을 다룸 |

```text
패스키 등록 -> 플랫폼에 키 저장 -> 필요 시 동기화 -> 로그인 시 생체/PIN 승인 -> 서버 서명 검증
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 등록 -> 키 생성/저장 -> 동기화 또는 보조 기기 준비 -> 로그인 요청 -> 로컬 사용자 확인 -> 서명 검증
```

1. **서비스 등록**: 사용자가 패스키 생성을 선택함
2. **키 생성과 저장**: 기기가 공개키와 개인키를 만들고 개인키를 안전하게 보관함
3. **동기화와 준비**: 필요 시 같은 계정의 다른 기기에서도 쓸 수 있게 함
4. **로컬 사용자 확인**: 지문이나 얼굴이나 PIN으로 사용자를 확인함
5. **서명 검증**: 서버가 공개키로 확인해 로그인시킴

## Ⅵ. 실무 적용 및 유의점

1. 대규모 소비자 서비스는 계정 복구와 예비 로그인 경로를 엄격히 설계하고 비밀번호 사용률 감소·계정 탈취 감소·복구 악용 부재로 확인함
2. 기업 환경은 MDM과 조건부 접근 정책을 함께 두고 관리 대상 기기 비율·분실 기기 회수·폐기 절차 준수 여부로 확인함

## Ⅶ. 결론

- 패스키는 FIDO2를 대중적으로 쓰기 쉽게 만든 운영 형태이므로 동기화 계정 보호와 복구 정책을 함께 설계해야 함
