## 미리 알고가기

- Shadow IT는 보안팀 승인 없이 현업이 직접 쓰는 SaaS와 클라우드 서비스를 말함
- 인라인 프록시는 사용자 요청 경로에 직접 들어가 실시간으로 허용·차단하는 방식임
- API 연동 방식은 SaaS가 제공하는 관리 API로 파일, 계정, 공유 상태를 사후 점검하는 방식임

## Ⅰ. 개요

- **정의/개념**: CASB는 사용자와 클라우드 서비스 사이에서 접근·데이터·위협 정책을 집행해 SaaS 사용을 가시화하고 통제하는 중개 계층임
- **배경/필요성**: SaaS 사용이 늘면서 데이터가 사내망 밖으로 이동함. 기존 방화벽만으로는 SaaS 업로드와 공유를 보기 어려움

## Ⅱ. 특징

- 승인 SaaS와 미승인 SaaS를 함께 식별함
- 업로드, 다운로드, 공유, 세션을 서비스별 정책으로 통제함
- DLP와 계정 이상행위 탐지를 함께 적용해 데이터 유출과 계정 오용을 줄임
- 인라인 프록시와 API 연동을 함께 써야 실시간 통제와 사후 점검을 동시에 수행하기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 인라인 프록시형 CASB | API 연동형 CASB |
|:---|:---|:---|
| 통제 시점 | 접속 순간에 바로 차단·허용함 | 저장된 파일과 설정을 사후 점검함 |
| 강점 | 업로드·다운로드·세션 제어에 강함 | 대규모 SaaS 자산 점검과 공유 상태 분석에 강함 |
| 한계 | 우회 경로와 사용자 경험 영향을 함께 봐야 함 | API 범위와 반영 지연에 영향을 받음 |
| 적합 환경 | 실시간 반출 통제가 중요한 환경 | SaaS 설정 감사가 중요한 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가시성 엔진 | 사용자, 기기, SaaS 사용 현황을 수집해 승인 여부와 위험도를 분류함 |
| 정책 엔진 | 사용자 그룹, 파일 유형, 위치, 기기 상태에 따라 허용·차단 규칙을 적용함 |
| 데이터 보호 | 민감정보 탐지, 암호화, 공유 제한, 다운로드 차단으로 반출을 통제함 |
| 위협 분석 | 계정 탈취 징후, 비정상 로그인, 대량 다운로드 같은 이상행위를 찾음 |
| 서비스 연동 | SSO, IdP, DLP, SaaS API와 연결해 정책 집행 범위를 넓힘 |

```text
사용자/기기 -> CASB 정책 판단 -> SaaS 접근 허용/차단
                     |
                     +-> 파일 검사/DLP
                     +-> 로그 수집/이상행위 분석
```

## Ⅴ. 원리 및 절차 흐름도

```text
클라우드 접근 식별 -> 사용자·기기·파일 맥락 확인 -> 정책 적용 -> SaaS 동작 허용/차단 -> 로그와 공유 상태 재점검
```

1. **접근 식별**: 사용자와 기기의 SaaS 접속을 수집함
2. **맥락 확인**: 사용자 역할, 기기 신뢰도, 파일 민감도, 위치 정보를 확인함
3. **정책 적용**: 업로드, 다운로드, 공유, 세션 제어 정책을 적용함
4. **동작 허용·차단**: 조건에 맞지 않으면 즉시 차단하거나 읽기 전용으로 전환함
5. **사후 재점검**: API 연동으로 파일 공유와 권한 변경 상태를 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 외부 협업용 SaaS가 많은 조직은 미승인 서비스와 과도한 공유 링크를 줄이고 비승인 SaaS 차단 수와 외부 공개 파일 수로 확인함
2. API 연동만 쓰면 실시간 업로드 통제가 비므로 핵심 SaaS는 인라인 제어를 병행하고 정책 우회 시도와 예외 승인 잔량으로 점검함

## Ⅶ. 결론

- CASB는 SaaS 접근과 데이터 반출을 같은 지점에서 통제하는 계층이므로 서비스 특성에 맞는 연동 방식 조합이 핵심임
