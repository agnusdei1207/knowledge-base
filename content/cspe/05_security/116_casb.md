## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 사용자와 클라우드 서비스 사이에 위치하여 가시성·컴플라이언스·위협 방어·데이터 보호를 제공하는 보안 중개 솔루션임 |
| **배경/필요성** | Shadow IT(미승인 SaaS) 사용 증가로 기업 데이터가 통제 밖으로 유출되며, 클라우드 사용에 대한 가시성·통제가 필요함 |
| **출제 의도** | CASB의 4대 기능과 배포 모드(프록시·API)의 차이를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 가시성   | --> | 컴플라이  | --> | 위협방어  |
| (Shadow  |     | 언스     |     | (DLP)    |
|  IT탐지) |     |          |     |          |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 가시성 | 승인·미승인 클라우드 서비스 사용 현황을 탐지·분류함 | 사무실 출입 기록 |
| 컴플라이언스 | 규제(개인정보보호법·PCI-DSS)에 따른 데이터 처리 정책을 강제함 | 법규 준수 감사관 |
| 위협 방어·DLP | 멀웨어·이상 행위를 탐지하고, 민감 데이터의 클라우드 업로드·공유를 통제함 | 보안 검색대 + 반출 검사 |

> 요약: 가시성(탐지) + 컴플라이언스(규제) + 위협 방어·DLP(차단)로 클라우드 사용을 보안 통제함.

## Ⅲ. 절차
```
+------------+     +------------+
| 클라우드   | --> | CASB      |
| 트래픽수집 |     | 정책적용   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 대시보드   | <-- | 위협탐지  |
| 보고·알림  |     | DLP적용   |
+------------+     +------------+
```

1. 트래픽 수집: 프록시 모드(인라인) 또는 API 모드(아웃오브밴드)로 클라우드 트래픽을 수집함
2. 정책 적용: 승인·미승인 서비스 분류, 접근 제어, 암호화 정책을 적용함
3. 위협 탐지·DLP: 멀웨어 스캔, 이상 다운로드 탐지, 민감 데이터 패턴(PII·PCI)을 식별·차단함
4. 대시보드 보고: Shadow IT 현황·정책 위반·위협 이벤트를 대시보드로 보고·알림함

> 요약: 수집 → 정책 적용 → 위협 탐지 → 보고로 클라우드 서비스 사용을 가시화·통제함.

## Ⅳ. 문제점
- 프록시 성능: 인라인 프록시 모드에서 트래픽 증가 시 지연이 발생함
- API 모드 한계: 실시간 차단이 불가하여 사후 탐지에 그침
- SaaS 커버리지: 수만 개 SaaS 서비스를 모두 커버하기 어렵고 신규 서비스 대응이 지연됨

## Ⅴ. 개선방안
- (단기) 하이브리드 배포: 프록시+API 모드를 병행하여 실시간 차단과 넓은 커버리지를 동시 확보함
- (중기) SASE 통합: CASB를 SWG·ZTNA·FWaaS와 함께 SASE 플랫폼에 통합함
- (장기) AI 기반 Shadow IT 탐지: ML로 신규·미분류 SaaS를 자동 식별하고 리스크를 평가함

## Ⅵ. 전망
- CASB가 SASE/SSE의 핵심 구성요소로 통합되며, SaaS 보안 관리(SSPM)와 결합하여 클라우드 데이터 보호의 중심축이 될 전망임
