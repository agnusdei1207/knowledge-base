# 📖 【암기용】 개념 완전 이해

> 목적: CASB를 처음 보는 사람도 SaaS 사용 통제와 데이터 보호 역할을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: CASB는 사용자와 클라우드 서비스 사이에서 SaaS 사용, 데이터 이동, 위협을 통제하는 보안 중개 계층임
- **왜 필요한가**: 조직 사용자는 승인되지 않은 SaaS에 파일을 올리고, 외부 공유 링크를 만들고, 개인 계정으로 업무 데이터를 반출할 수 있다. 방화벽만으로는 SaaS API 내부 행위를 보기 어렵다.
- **핵심 직관**: 회사 문서가 어떤 클라우드 앱으로 나가고 누구에게 공유되는지 검사하는 보안 검문소임

## 깊이 이해
- **배경·문제의식**: SaaS 도입이 늘면 Shadow IT, 외부 공유, OAuth 앱 권한 남용, 데이터 유출이 발생한다. 기존 프록시와 방화벽은 URL 접속 여부는 보지만 SaaS 내부 파일·권한·공유 상태를 세밀하게 통제하지 못한다.
- **작동 원리**: CASB는 API 연동, Forward Proxy, Reverse Proxy, 로그 분석 방식으로 SaaS 사용을 관측한다. 사용자, 단말, 위치, 파일 민감도, 앱 위험 등급을 평가하여 허용, 차단, 암호화, DLP, 격리, 공유 취소를 수행한다.
- **비유**: 택배 물류센터에서 상자 목적지와 내용물 등급을 확인해 반출 금지 물품은 멈추고, 허용 물품은 송장과 추적번호를 남기는 구조임
- **구체 예시**: 임직원이 주민등록번호 100건 포함 파일을 개인 Google Drive에 업로드하면 CASB가 DLP 정책으로 업로드를 차단하고 SIEM에 5분 이내 이벤트를 전송함
- **흔한 오해·주의점**: CASB는 CSPM이나 CWPP와 다르다. CASB는 SaaS 접근과 데이터 사용 통제에 초점, CSPM은 클라우드 형상 점검, CWPP는 워크로드 보호가 중심임

## 연결 개념
- DLP — 파일 내용 기반 유출 방지 정책
- SWG/SSE/SASE — 웹·SaaS 접근 보안 엣지 구성
- OAuth App Governance — SaaS 연동 앱 권한 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CASB는 "클라우드 방화벽"이 아니라 SaaS 가시성, 데이터 보호, 위협 탐지, 규정 준수를 API와 프록시 방식으로 수행하는 통제 지점임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CASB(Cloud Access Security Broker)는 사용자와 클라우드 서비스 사이에서 SaaS 접근, 데이터, 행위를 정책 기반으로 통제하는 보안 브로커이다.
> 2. **가치**: Shadow IT 식별, DLP, 외부 공유 통제, OAuth 앱 감시로 클라우드 데이터 유출 경로를 줄인다.
> 3. **판단 포인트**: API 방식과 프록시 방식을 목적별로 조합하고 DLP 오탐률, SaaS 커버리지, 대응시간으로 운영해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SaaS 보안 통제 이해 확인 | Shadow IT, DLP, 접근 제어, 위협 탐지, 규정 준수 | 방화벽·WAF와 동일하게 설명 |
| 배치 방식 판단 확인 | API, Forward Proxy, Reverse Proxy, Log 수집 방식 | SaaS 내부 공유·권한 통제 누락 |
| 운영 지표 제시 확인 | 앱 커버리지, DLP 오탐률, 외부 공유 조치시간 | 제품명 나열 후 정책·지표 부재 |

> 요약: CASB 답안은 SaaS 데이터 이동과 사용자 행위를 통제하는 구조와 배치 방식을 함께 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: SaaS 접근·데이터 통제
- 배경: 업무 SaaS와 개인 클라우드 사용이 늘면서 Shadow IT, 외부 공유 링크, OAuth 권한 남용, 민감정보 반출 위험이 증가했다.
- 필요성: CASB는 사용자, 단말, 앱, 데이터 민감도를 기준으로 접근·업로드·공유·다운로드 정책을 집행하고 DLP 탐지 로그를 감사해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User/Device -> CASB Proxy/API -> SaaS Application
                    +-> DLP/Policy Engine
                    +-> Threat Detection
                    +-> SIEM/SOAR
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Discovery | Shadow IT와 SaaS 사용량 식별 | 방화벽 로그, SWG 로그, CASB 리포트 |
| Policy Engine | 사용자, 단말, 위치, 앱 위험도 기반 정책 판단 | RBAC, ABAC, 위험 점수 연계 |
| DLP/Classification | 민감정보 탐지와 반출 통제 | 주민번호, 카드번호, 기밀 라벨 |
| API Connector | SaaS 내부 파일·공유·권한 점검 | Microsoft 365, Google Workspace, Salesforce |
| Proxy Control | 실시간 업로드·다운로드·세션 제어 | Forward/Reverse Proxy 방식 |

> 요약: CASB는 SaaS 발견, 정책 판단, DLP, API 점검, 프록시 통제를 결합해 클라우드 사용을 제어한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
SaaS 사용 탐지 -> 앱 위험도 평가 -> 사용자/단말 정책 확인
-> 파일 내용 DLP 검사 -> 허용/차단/격리/암호화
-> 로그 전송 -> 공유 권한 정정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 로그와 API로 SaaS 사용 현황 식별 | 승인 앱 등록률 100%, 미승인 앱 주간 리포트 |
| 2 | 앱 위험도와 사용자 권한 평가 | 위험 등급 High 앱 업로드 차단 |
| 3 | 파일 내용과 라벨을 DLP로 검사 | 개인정보 패턴 95% 이상 탐지 기준 |
| 4 | 정책에 따라 차단, 격리, 암호화, 공유 취소 | Critical 이벤트 15분 이내 티켓 생성 |
| 5 | SIEM/SOAR에 이벤트 전송 후 추적 | 로그 수집 지연 p95 5분 이하 |

> 요약: CASB는 SaaS 행위를 발견하고 데이터 민감도와 앱 위험도를 결합해 실시간 또는 사후 조치를 수행한다.

## Ⅳ. 특징

| 구분 | 기존 웹 보안 | CASB | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 가시성 | URL·도메인 접속 로그 | SaaS 내부 파일, 공유, OAuth 권한 | 승인 SaaS 커버리지 95% 이상 |
| 통제 방식 | 차단·허용 중심 | 업로드, 다운로드, 공유, 격리, 암호화 | DLP 오탐률 3% 이하 |
| 배치 | 프록시·방화벽 | API+Forward/Reverse Proxy 조합 | 실시간 통제는 Proxy 필요 |
| 대상 | 웹 접속 | SaaS 데이터와 사용자 행위 | Microsoft 365, Google Workspace 우선 |

> 요약: CASB는 SaaS 내부 데이터와 권한 상태를 통제하므로 URL 차단 중심 보안과 적용 지점이 다르다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | SWG·방화벽 URL 통제 | CASB API+Proxy 통제 | SaaS 사용 비중 50% 이상, 외부 공유 빈도 높음 |
| 비용/운영 | 네트워크 로그 중심 | SaaS API 권한, DLP 정책, 예외 관리 | 주요 SaaS 5개 이상 연동 가능성 |
| 위험 | 접속 여부만 확인 | 데이터 내용과 공유 권한까지 확인 | 개인정보·영업비밀 반출 통제 필요 |

> 요약: SaaS 내부 파일과 공유 권한을 통제해야 하면 CASB가 SWG 단독 구성보다 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| DLP 오탐 | 정규식·사전 기반 탐지 과다 | 라벨링, 예외 승인, 샘플 검증 | 오탐률 3% 이하 |
| SaaS 사각지대 | API 미지원 앱, 개인 계정 사용 | SWG 로그 연계, Shadow IT 차단 | 미승인 앱 월 10건 이하 |
| 권한 과다 | OAuth 앱과 외부 공유 장기 방치 | OAuth 권한 리뷰, 외부 공유 만료 | 90일 이상 공유 링크 0건 |

> 요약: CASB 운영 리스크는 DLP 오탐, SaaS 사각지대, 권한 과다이며 정책 튜닝과 정기 리뷰로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| SaaS 커버리지 | 주요 SaaS API 연동 95% 이상 | CASB 콘솔, SaaS 관리자 API |
| 데이터 보호 | 민감파일 외부 공유 24시간 이내 조치 | DLP 이벤트, 티켓 |
| 위협 대응 | 계정 이상행위 탐지 후 15분 이내 SOAR 실행 | UEBA, SIEM, SOAR 로그 |

> 요약: CASB 성과는 SaaS 커버리지, 민감파일 조치시간, 이상행위 대응시간으로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 방화벽·SWG 로그로 Shadow IT를 식별하고 Microsoft 365, Google Workspace, Salesforce부터 API 연동률 95% 이상 확보함
2. 개인정보, 기밀 라벨, 외부 공유, 개인 계정 업로드 정책을 정의하고 DLP 오탐률 3% 이하까지 4주 단위로 튜닝함
3. OAuth 앱 권한, 외부 공유 링크, 고위험 다운로드 이벤트를 SIEM/SOAR에 연계해 Critical 이벤트는 15분 이내 조치함

**결론 (2줄):**
- 기술사 판단: SaaS 데이터 유출 위험이 핵심이면 CASB API와 Proxy를 조합하고, 단순 웹 접속 통제면 SWG 중심 구성이 적합함
- 향후 방향: CASB는 SSE/SASE에 통합되어 ZTNA, SWG, DLP, UEBA와 단일 정책 체계로 운영됨
