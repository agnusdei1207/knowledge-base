## Ⅰ. 개요
- **정의**: 사용자와 클라우드 서비스 사이에 위치하여 보안 정책을 중개·적용하는 보안 솔루션임
- **배경/필요성**: SaaS 이용이 증가하면서 IT 부서가 인지하지 못하는 Shadow IT와 데이터 유출 경로가 확대되어 클라우드 접근 통제가 필요함
- **비유**: 회사와 외부 클라우드 사이에 보안 경비원을 배치하여 출입과 반출을 관리하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 4대 기능 이해와 SASE 내 위치 | 가시성, 규정준수, 위협방지, 데이터보안 | CASB 배치 모드(API/Proxy) 구분 |

> 요약: CASB는 사용자-클라우드 간 보안 정책을 중개하여 Shadow IT와 데이터 유출을 통제하는 브로커임

## Ⅱ. 구성요소
```text
사용자 --> Forward Proxy --> CASB --> SaaS/IaaS
                              |
              +---------------+---------------+
              |               |               |
         가시성 엔진    정책 적용 엔진   위협 탐지 엔진
              |               |               |
         Shadow IT 탐색   DLP/암호화     UEBA/멀웨어
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 가시성(Visibility) | 조직 내 클라우드 서비스 사용 현황을 식별하고 Shadow IT를 탐지함 | 출입 기록부 |
| 규정 준수(Compliance) | 데이터 보관 위치, 접근 권한 등을 규정에 맞게 통제함 | 규정 감사관 |
| 데이터 보안(Data Security) | DLP, 암호화, 토큰화로 민감 데이터 유출을 방지함 | 반출 검사대 |
| 위협 방지(Threat Protection) | 악성코드 탐지, 이상 행동 분석으로 클라우드 위협을 차단함 | 침입 경보기 |

> 요약: 가시성, 규정준수, 데이터보안, 위협방지 4대 기능으로 클라우드 접근을 통제함

## Ⅲ. 절차
```text
클라우드 식별 -> 정책 수립 -> 트래픽 중개 -> 위반 대응
```
- 1단계: API 또는 로그 수집으로 조직 내 사용 중인 클라우드 서비스를 식별(Discovery)함
- 2단계: 데이터 분류, 접근 권한, 공유 범위 등 보안 정책을 CASB에 설정함
- 3단계: Forward/Reverse Proxy 또는 API 모드로 트래픽을 중개하며 정책을 실시간 적용함
- 4단계: 정책 위반 시 차단, 알림, 격리 등 자동 대응 조치를 수행함

> 요약: 식별, 정책 수립, 트래픽 중개, 위반 대응의 4단계로 클라우드 보안을 이행함

## Ⅳ. 문제점
- API 모드 한계: API 기반 배치는 실시간 차단이 불가하고 사후 탐지만 가능함
- 암호화 트래픽 처리 부하: TLS 복호화 후 재암호화 과정에서 지연이 발생함
- 멀티 SaaS 커버리지: 비표준 SaaS 서비스에 대한 정책 적용이 제한적임

> 요약: API 모드 실시간 한계, 암호화 부하, SaaS 커버리지가 CASB의 주요 과제임

## Ⅴ. 개선방안
1. 단기: Inline Proxy + API 하이브리드 배치로 실시간 차단과 사후 분석을 병행함
2. 중기: 하드웨어 가속 TLS 처리 도입으로 복호화 지연을 최소화함
3. 장기: SASE(073 참조) 아키텍처에 CASB를 통합하여 전체 SaaS를 단일 정책으로 관리함

> 요약: 하이브리드 배치, TLS 가속, SASE 통합으로 CASB 효용을 극대화해야 함

## Ⅵ. 전망
- 발전 방향: SSE(Secure Service Edge) 핵심 구성요소로 SWG, ZTNA와 통합이 가속될 전망임
- 기술사적 판단: 클라우드 중심 보안 아키텍처에서 CASB는 데이터 흐름 통제의 중추로 유지될 것임
- 기술사 제언: CASB 도입 시 기존 DLP·SIEM과의 연동 로드맵을 함께 수립해야 함
