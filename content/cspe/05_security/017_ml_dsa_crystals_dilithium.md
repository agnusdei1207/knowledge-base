## 미리 알고가기

- 전자서명: 메시지의 무결성과 서명자 신원을 함께 확인하는 공개키 기반 검증 방식임
- MSIS: 짧은 벡터를 찾는 격자 문제로, 위조 서명 생성이 어렵다는 근거가 됨
- Fiat-Shamir with Aborts: 임시 서명값이 안전 범위를 벗어나면 버리고 다시 만드는 서명 절차임
- 인증서 체인: 서버 인증서와 중간 CA를 함께 내려 보내는 검증 경로임

## Ⅰ. 개요

- **정의/개념**: ML-DSA는 격자 기반 난제를 이용한 PQC 전자서명 표준임. 양자 공격에 대비해 서명 생성과 검증을 수행함
- **배경/필요성**: 인증서·코드 서명·전자문서는 RSA와 ECDSA에 의존함. 양자 시대에도 신원 검증을 유지할 서명 방식이 필요함

## Ⅱ. 특징

- 키 교환이 아니라 서명 알고리즘이므로 ML-KEM과 역할이 다름
- 격자 기반이면서 서명·검증 속도가 비교적 빨라 범용 인증에 맞음
- 서명값과 공개키가 ECDSA보다 커 인증서 체인과 배포 파일을 키움
- 전환기에는 이중 서명이나 일부 신뢰 경로 우선 적용이 현실적임

## Ⅲ. 종류 및 비교

| 판단 기준 | ECDSA | ML-DSA |
|:---|:---|:---|
| 양자 공격 대응 | 이산대수 기반이라 양자 공격에 취약함 | 격자 기반 난제로 설계되어 양자 공격 대응을 전제로 함 |
| 서명 크기 | 서명 크기가 작아 네트워크와 저장소 부담이 낮음 | 서명과 공개키가 커서 인증서 체인과 배포 패키지가 비대해짐 |
| 성숙도 | PKI, 전자문서, 코드 서명 생태계에 깊게 자리 잡음 | 표준화는 완료됐지만 운영 도구와 중간 장비 지원은 전환 중임 |
| 적용 판단 | 레거시 호환성이 가장 중요한 환경에 맞음 | 장기 무결성과 PQC 마이그레이션이 중요한 환경에 맞음 |

> 요약: ECDSA는 가볍고 익숙하지만 양자 취약성이 있고, ML-DSA는 크기 부담이 커지는 대신 장기 서명 신뢰를 지키는 방향임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 공개키 | 검증자가 서명 진위를 확인할 때 쓰는 값이며, 인증서 크기와 배포 비용에 직접 영향을 줌 |
| 비밀키 | 서명자가 서명을 생성할 때 쓰는 핵심 값이며, 유출되면 위조 서명을 막을 수 없으므로 보호 저장소가 필수임 |
| 메시지 해시 | 원문 전체 대신 서명 대상 요약값을 계산해 서명 처리량을 줄이고 메시지 경계를 고정하는 역할을 함 |
| 서명값 | 검증자가 공개키로 확인하는 결과물이며, 크기가 커질수록 네트워크와 저장소 설계에 부담이 생김 |

```text
+--------+     +-------------+     +--------+     +--------+
| 원문   | --> | 메시지 해시 | --> | 서명 생성 | --> | 서명값 |
+--------+     +-------------+     +--------+     +--------+
                                                   |
                                           +---------------+
                                           | 공개키로 검증 |
                                           +---------------+
```

> 요약: 원문 해시를 비밀키로 서명하고 공개키로 검증하는 구조이며, 공개키와 서명 크기가 운영 설계의 핵심 변수임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------------+     +----------+     +----------+
| 키 생성  | --> | 해시 계산 | --> | 서명 생성 시도  | --> | 조건 검사 | --> | 서명 검증 |
+----------+     +----------+     +----------------+     +----------+     +----------+
```

1. **키 생성**: 서명자용 비밀키와 검증자용 공개키를 생성함
2. **해시 계산**: 메시지를 고정 길이 해시로 정리함
3. **서명 생성 시도**: 난수와 비밀키를 사용해 임시 서명값을 만듦
4. **조건 검사**: 임시 값이 안전 범위를 벗어나면 버리고 다시 생성함
5. **서명 검증**: 검증자가 공개키와 메시지 해시로 최종 서명을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 서버 인증서·코드 서명은 체인 축소와 이중 서명을 설계하고 핸드셰이크 크기·배포 시간·검증 지연으로 확인함
2. IoT 펌웨어는 검증 라이브러리를 경량화하고 파라미터를 구분해 검증 성공률·부팅 시간·메모리로 확인함

## Ⅶ. 결론

- ML-DSA는 양자 시대 범용 서명 표준이므로 서명 크기와 인증서 생태계 전환 비용을 함께 판단해야 함
