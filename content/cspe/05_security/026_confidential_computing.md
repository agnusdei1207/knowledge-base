## 미리 알고가기

- Data in Use: CPU와 메모리에서 실제로 처리 중인 데이터 상태를 뜻함
- Enclave: 일반 시스템으로부터 격리된 실행 구역임
- Confidential VM: VM 전체 메모리를 암호화해 테넌트 워크로드를 보호하는 방식임
- Remote Attestation: 원격 사용자가 현재 격리 환경과 코드 무결성을 확인하는 절차임

## Ⅰ. 개요

- **정의/개념**: 기밀 컴퓨팅은 TEE를 서버·클라우드로 확장한 실행 아키텍처임. 사용 중 데이터와 코드 무결성을 보호함
- **배경/필요성**: 저장·전송 암호화만으로는 메모리 평문 노출을 막기 어려움. 클라우드 운영자·내부자 위험까지 고려해야 함

## Ⅱ. 특징

- 연산 중 메모리까지 보호 범위에 넣어 기존 클라우드 암호화와 다름
- 하드웨어 격리를 활용해 동형 암호보다 실용 성능이 높음
- 신뢰 출발점이 원격 증명과 펌웨어 무결성에 있음
- 앱 일부 격리와 VM 전체 보호 중 워크로드 성격에 따라 선택함

## Ⅲ. 종류 및 비교

| 판단 기준 | 애플리케이션 수준 격리 | VM 수준 격리 |
|:---|:---|:---|
| 보호 범위 | 민감한 코드 일부만 enclave로 잘라 넣어 보호함 | VM 메모리 전체를 암호화해 워크로드 전반을 보호함 |
| 도입 난이도 | 코드 수정과 SDK 적응이 필요해 개발 부담이 큼 | 기존 VM 이미지를 거의 그대로 올릴 수 있어 전환이 쉬움 |
| 보안 경계 | TCB를 작게 유지하기 쉬워 공격 표면을 줄이기 좋음 | OS와 일부 시스템 컴포넌트가 경계 안에 들어와 TCB가 커질 수 있음 |
| 적합한 환경 | 키 처리나 특정 알고리즘처럼 핵심 연산만 분리할 때 맞음 | 레거시 앱이나 데이터 분석 파이프라인 전체를 보호할 때 맞음 |

> 요약: 애플리케이션 수준 격리는 더 좁고 엄격하며, VM 수준 격리는 도입이 쉽고 범위가 넓음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TEE 하드웨어 | CPU와 메모리 암호화를 제공하는 기반이며 격리 수준과 성능 오버헤드를 결정함 |
| 원격 증명 | 격리 환경과 실행 코드가 기대한 값인지 확인하는 절차이며 키를 맡기기 전 신뢰 판단의 기준이 됨 |
| 키 브로커 | 증명 성공 시에만 복호화 키나 비밀값을 워크로드에 전달하는 제어 지점임 |
| 보호 워크로드 | 민감 데이터 분석, 모델 추론, 공동 분석 같은 실제 처리 작업이며 보호 범위 정의가 중요함 |

```text
+-------------+     +-------------+     +-----------+     +-------------+
| 원격 증명   | --> | 키 브로커    | --> | 격리 워크로드 | --> | 결과 반환    |
+-------------+     +-------------+     +-----------+     +-------------+
                                 |
                         +---------------+
                         | TEE 하드웨어  |
                         +---------------+
```

> 요약: 원격 증명으로 격리 환경을 확인한 뒤 키를 전달하고, TEE 안에서만 워크로드를 실행하는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 환경 기동 | --> | 원격 증명 | --> | 키 전달  | --> | 격리 연산 | --> | 결과 회수 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **환경 기동**: 보호할 VM이나 enclave를 시작함
2. **원격 증명**: 하드웨어와 코드 측정값을 외부 검증자에게 제출함
3. **키 전달**: 검증이 통과한 경우에만 비밀키와 토큰을 주입함
4. **격리 연산**: 보호 구역 안에서 데이터 처리와 모델 실행을 수행함
5. **결과 회수**: 필요한 결과만 밖으로 내보내고 메모리 내 민감값을 정리함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 공동 분석·AI 추론은 증명 정책과 CI/CD 무결성을 운영하고 attestation 성공률·작업 지연으로 확인함
2. GPU·드라이버 의존 워크로드는 보호 경계를 먼저 검증하고 성능 오버헤드·기능 호환성·노출 경로로 확인함

## Ⅶ. 결론

- 기밀 컴퓨팅은 외부 인프라에서 민감 연산을 처리할 때 유효하며 원격 증명과 지원 생태계 통제가 핵심임
