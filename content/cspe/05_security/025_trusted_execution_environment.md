## 미리 알고가기

- REE: 일반 운영체제와 앱이 동작하는 비신뢰 실행 영역임
- Secure World: TEE 안에서 신뢰된 코드만 실행되는 격리 영역임
- Trusted Application: TEE 안에서 돌아가는 보안 전용 애플리케이션임
- Attestation: 현재 실행 환경이 변조되지 않았음을 외부에 증명하는 절차임

## Ⅰ. 개요

- **정의/개념**: TEE는 핵심 코드와 데이터를 별도 격리 영역에서 실행해 기밀성과 무결성을 보호하는 하드웨어 기반 환경임
- **배경/필요성**: 모바일 결제, 생체 인증, 기기 키는 OS 침해 후에도 보호되어야 함. 일반 메모리 밖의 안전한 실행 구역이 필요함

## Ⅱ. 특징

- 일반 OS와 보안 기능을 분리해 루팅 후에도 핵심 자산 노출을 줄임
- HSM보다 범용 연산 성능이 높아 생체 인증, DRM, 결제 토큰 처리에 적합함
- 하드웨어 격리만으로 충분하지 않아 TA 품질과 부채널 대응이 필요함
- 모바일 단말뿐 아니라 서버형 TEE와 기밀 컴퓨팅 기반으로 확장됨

## Ⅲ. 종류 및 비교

| 판단 기준 | Secure Element | TEE |
|:---|:---|:---|
| 구현 위치 | 별도 보안 칩에 기능을 분리함 | 메인 프로세서 안에 격리 영역을 둠 |
| 성능 특성 | 보안성은 강하지만 범용 연산 성능이 낮음 | 보안성과 성능 균형이 좋아 앱 연산과 연계하기 쉬움 |
| 활용 범위 | 카드 보안, 단순 키 저장, 제한된 보안 연산에 맞음 | 생체 인증, DRM, 모바일 결제, 단말 보안 서비스에 맞음 |
| 운영 핵심 | 물리 칩 통제와 인터페이스 보호가 중요함 | Secure World 코드 품질과 REE 경계 제어가 중요함 |

> 요약: Secure Element는 전용 칩 중심이고, TEE는 메인 프로세서 성능을 활용한 격리 실행 환경임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| REE | 일반 앱과 운영체제가 동작하는 영역이며 TEE와 직접 메모리를 공유하지 않도록 경계를 둠 |
| Secure World | 민감 연산을 수행하는 격리 영역이며 일반 OS가 침해돼도 직접 읽거나 쓰지 못하게 설계됨 |
| Trusted Application | 지문 매칭, 키 연산, 결제 토큰 처리처럼 제한된 보안 기능만 수행하는 코드 단위임 |
| Secure Monitor | REE와 Secure World 사이 전환을 제어하는 계층이며 허용된 호출만 통과시켜 경계를 지킴 |

```text
+------+        +----------------+        +-------------------+
| REE  | -----> | Secure Monitor | -----> | Secure World / TA |
+------+        +----------------+        +-------------------+
     ^                                              |
     +---------------- 결과만 반환 ------------------+
```

> 요약: 일반 영역 요청은 Secure Monitor를 거쳐 TEE 안의 신뢰 애플리케이션에서만 처리되고 결과만 밖으로 나옴.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 요청 생성 | --> | 세계 전환 | --> | 안전 연산 | --> | 결과 봉인 | --> | 결과 반환 |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **요청 생성**: 일반 앱이 보안 연산 요청을 만듦
2. **세계 전환**: Secure Monitor가 호출을 받아 Secure World로 전환함
3. **안전 연산**: Trusted Application이 격리 메모리에서 키나 생체 데이터를 사용해 연산함
4. **결과 봉인**: 필요한 결과만 정리하고 내부 상태를 보호함
5. **결과 반환**: REE에는 승인 여부나 토큰 같은 최소 결과만 전달함

## Ⅵ. 실무 적용 및 유의점

1. 모바일 결제·생체 인증은 코드 서명과 원격 검증을 적용하고 인증 성공률·attestation 실패율·응답 지연으로 확인함
2. DRM·차량·IoT 키 보관은 constant-time 구현과 업데이트 체계를 운영하고 패치율·키 유출·무결성 결과로 확인함

## Ⅶ. 결론

- TEE는 OS 침해 후에도 핵심 연산을 지키는 격리 환경이므로 TA 품질, 원격 검증, 업데이트 체계가 실무 가치를 좌우함
