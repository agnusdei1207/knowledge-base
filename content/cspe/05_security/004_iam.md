## Ⅰ. 개요
- **정의**: 사용자·디바이스·서비스의 디지털 신원을 생성·관리하고 자원 접근 권한을 통합 제어하는 체계
- **배경/필요성**: 클라우드·SaaS 확산으로 분산된 계정·권한을 중앙에서 일관 관리할 필요가 증가함
- **비유**: 건물 관리실에서 전 직원의 출입증 발급·회수·권한 변경을 일괄 처리하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IAM 구성요소와 수명주기 관리 | 프로비저닝-인증-인가-감사의 전 과정 | IAM을 단순 SSO로만 설명하지 않을 것 |

> 요약: IAM은 디지털 신원의 전 수명주기를 통합 관리하는 보안 인프라임

## Ⅱ. 구성요소
```text
+-------------+     +----------+     +----------+     +--------+
| ID 저장소   |---->| 인증엔진 |---->| 인가엔진 |---->| 감사로그|
| (Directory) |     | (AuthN)  |     | (AuthZ)  |     | (Audit)|
+-------------+     +----------+     +----------+     +--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| ID 저장소 | LDAP·AD 등에 사용자·그룹·속성 정보를 저장·관리함 | 인사 DB에 직원 정보 등록 |
| 프로비저닝 | 입사·이동·퇴직에 따른 계정·권한의 생성·변경·삭제를 자동화함 | 출입증 발급·갱신·회수 |
| SSO/Federation | 한 번 인증으로 복수 시스템에 접근 가능하게 하는 통합 인증 체계임 | 하나의 마스터키로 여러 방 출입 |

> 요약: ID 저장소·프로비저닝·SSO·감사로그가 IAM의 핵심 구성요소임

## Ⅲ. 절차
```text
계정생성 --> 권한할당 --> 접근통제 --> 감사/폐기
```
- 1단계: **계정생성** — 사용자·서비스 계정을 ID 저장소에 등록함
- 2단계: **권한할당** — 역할·속성 기반으로 필요 최소 권한을 매핑함
- 3단계: **접근통제** — 인증·인가 엔진이 실시간 접근 요청을 판단함(003 참조)
- 4단계: **감사/폐기** — 접근 로그를 감사하고 불필요 계정·권한을 폐기함

> 요약: 계정 수명주기(생성→할당→통제→폐기)를 일관되게 관리하는 것이 IAM의 핵심임

## Ⅳ. 문제점
- 고아 계정: 퇴직·이동 후 미삭제 계정이 비인가 접근 경로로 남음
- 권한 크리프: 부서 이동 시 기존 권한이 회수되지 않아 과다 권한이 누적됨
- 사일로화: 온프레미스·클라우드 간 IAM이 분리되어 정책 일관성이 저하됨

> 요약: 고아 계정·권한 크리프·IAM 사일로가 운영상 주요 위험 요인임

## Ⅴ. 개선방안
1. 단기: 자동 프로비저닝/디프로비저닝으로 고아 계정 발생을 차단함
2. 중기: 분기별 접근 권한 재인증(Access Review)으로 권한 크리프를 통제함
3. 장기: 통합 IAM 플랫폼(IDaaS)으로 온프레미스·클라우드 정책을 일원화함

> 요약: 자동화·정기 재인증·IDaaS 통합으로 IAM 운영 리스크를 저감함

## Ⅵ. 전망
- 발전 방향: AI 기반 이상 행위 탐지와 적응형 접근제어가 IAM에 통합됨
- 기술사적 판단: IAM은 제로트러스트(007 참조)·PAM(005 참조)의 기반 인프라임
- 기술사 제언: 클라우드 전환 시 IDaaS 도입과 최소 권한 원칙 적용을 우선 과제로 권고함
