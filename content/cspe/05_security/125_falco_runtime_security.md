## 미리 알고가기

- 런타임은 컨테이너와 프로세스가 실제로 실행 중인 상태를 말함
- 시스템 콜은 프로세스가 파일 접근이나 네트워크 연결처럼 커널에 요청하는 기본 동작임
- eBPF는 커널 이벤트를 비교적 가볍게 관찰할 수 있게 해 주는 리눅스 기술임

## Ⅰ. 개요

- **정의/개념**: Falco는 리눅스 커널 이벤트와 시스템 콜을 바탕으로 컨테이너와 호스트의 비정상 행위를 실시간 탐지하는 런타임 보안 도구임
- **배경/필요성**: 이미지 스캔과 배포 정책을 통과한 워크로드도 실행 후 침해될 수 있음. 운영 중 행위 감시가 필요함

## Ⅱ. 특징

- 파일 접근, 쉘 실행, 권한 상승, 외부 연결 같은 행위를 커널 수준에서 감시함
- 시그니처보다 행위 규칙에 강해 알려지지 않은 침해 징후도 잡기 쉬움
- 컨테이너 메타데이터를 붙여 파드와 네임스페이스 맥락을 바로 파악함
- 규칙을 너무 넓게 잡으면 경보가 과도해지므로 정상 행위 기준선 정리가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 이미지 스캔 | Falco |
|:---|:---|:---|
| 보는 시점 | 배포 전 | 배포 후 |
| 보는 대상 | 취약 패키지와 잘못된 이미지 구성 | 실행 중 프로세스와 시스템 콜 |
| 강점 | 위험한 산출물 사전 차단 | 침해 후 비정상 행위 실시간 탐지 |
| 한계 | 실행 중 공격은 직접 못 봄 | 사전 취약점 자체를 없애지는 못함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 수집기 | eBPF나 커널 모듈로 시스템 콜과 커널 이벤트를 수집함 |
| 규칙 엔진 | 허용되지 않은 파일 접근, 쉘 실행, 권한 상승 규칙을 평가함 |
| 메타데이터 보강 | 컨테이너, 파드, 네임스페이스 정보를 붙여 경보 맥락을 만듦 |
| 출력 채널 | 로그, 웹훅, SIEM, 메시지 큐로 경보를 전달함 |
| 대응 연계 | 격리, 티켓 발행, 조사 자동화와 연결함 |

```text
커널 이벤트 수집 -> 규칙 평가 -> 컨테이너 맥락 보강 -> 경보 전송 -> 대응 연계
```

## Ⅴ. 원리 및 절차 흐름도

```text
워크로드 실행 -> 시스템 콜 발생 -> 규칙 대조 -> 위반 탐지 -> 경보 또는 격리 -> 조사
```

1. **워크로드 실행**: 컨테이너와 프로세스가 정상 업무를 수행함
2. **이벤트 수집**: 파일 접근과 프로세스 생성과 네트워크 연결을 모음
3. **규칙 대조**: 허용되지 않은 행위와 비교함
4. **위반 탐지**: 쉘 실행, 민감 파일 접근, 권한 상승 같은 이상행위를 찾음
5. **경보와 대응**: SIEM 연계나 격리 조치로 후속 대응을 수행함

## Ⅵ. 실무 적용 및 유의점

1. 인터넷 노출 워크로드는 런타임 쉘 실행과 민감 파일 접근을 감시하고 고위험 경보 탐지 시간과 실제 사고 전환 비율로 확인함
2. 정상 운영 명령까지 잡히면 경보가 무뎌지므로 배포 도구와 백업 작업 허용 행위를 정리하고 반복 오탐 건수로 점검함

## Ⅶ. 결론

- Falco는 배포 전 검사로 남는 빈틈을 실행 행위에서 메우는 도구이므로 탐지 범위보다도 정확한 규칙 설계와 대응 연계가 더 중요함
