## 미리 알고가기

- 최소 권한은 업무에 필요한 범위까지만 권한을 주는 원칙이고, 직무 분리는 상충 업무를 한 사람에게 몰아주지 않는 원칙임
- 최소 권한이 사고 확산을 줄인다면 직무 분리는 부정 행위와 단독 남용을 줄이는 데 초점이 있음
- 두 원칙은 따로 존재하는 것이 아니라 권한 설계와 운영 감사에서 함께 적용돼야 함

## Ⅰ. 개요

- **정의/개념**: 최소 권한·직무 분리는 필요한 권한만 부여하고 상충 업무를 둘 이상의 역할로 나눠 단독 수행을 막는 접근 통제 원칙임
- **배경/필요성**: 과다 권한과 단독 승인 구조는 계정 탈취와 내부 부정 발생 시 피해를 키움. 권한 축소와 상호 견제가 필요함

## Ⅱ. 특징

- 최소 권한은 상시 접근 범위를 줄여 사고 영향 반경을 축소함
- 직무 분리는 작성과 승인, 개발과 배포 같은 상충 업무를 나눠 부정을 억제함
- 두 원칙 모두 운영 단계의 예외 승인과 정기 리뷰가 중요함
- 인력 부족이나 프로젝트 예외가 누적되면 원칙이 형식화되기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 최소 권한 | 직무 분리 |
|:---|:---|:---|
| 주된 목적 | 과다 접근 축소 | 단독 부정과 충돌 방지 |
| 적용 대상 | 계정별 권한 범위 | 역할 조합과 승인 절차 |
| 대표 사례 | 읽기만 필요한 계정에 수정 권한 제거 | 발주자와 승인자 분리 |
| 운영 포인트 | 정기 회수와 JIT | SoD 규칙과 예외 관리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Role and Permission Model | 업무별 필요한 권한과 상충 역할을 정의함 |
| SoD Rules | 동시에 가지면 안 되는 역할 조합을 정함 |
| Approval and Exception | 예외 부여와 기간과 승인 근거를 관리함 |
| Periodic Review | 권한 누적과 SoD 위반을 정기 점검함 |

```text
업무 분석 -> 최소 권한 설계 -> SoD 규칙 정의 -> 부여/예외 승인 -> 정기 리뷰와 회수
```

## Ⅴ. 원리 및 절차 흐름도

```text
직무 정의 -> 권한 부여 -> 상충 역할 검사 -> 업무 수행 -> 감사/재검토 -> 권한 조정
```

1. **직무 정의**: 업무 흐름과 승인 단계를 분석함
2. **권한 부여**: 필요한 권한만 역할에 매핑함
3. **상충 역할 검사**: 금지 조합을 사전에 차단함
4. **업무 수행**: 필요한 기간만 권한을 사용하게 함
5. **감사와 조정**: 위반과 누적 권한을 찾아 회수함

## Ⅵ. 실무 적용 및 유의점

1. 재무·구매·인사 승인 업무는 최소 권한과 SoD를 함께 적용하고 상충 역할 동시 보유 감소·예외 승인 적정성으로 확인함
2. 개발·배포 체계는 자동화 계정까지 점검하고 운영 직접 배포 계정 축소·긴급 예외 후 권한 원복 여부로 확인함

## Ⅶ. 결론

- 최소 권한과 직무 분리는 권한 남용과 부정 행위를 함께 줄이는 원칙이므로 예외와 리뷰까지 포함해 운영해야 함
