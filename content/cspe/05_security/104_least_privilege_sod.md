## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 최소 권한은 업무 수행에 필요한 최소한의 권한만 부여하는 원칙이며, 직무 분리는 핵심 업무를 2인 이상에 분산하여 단독 남용을 방지하는 원칙임 |
| **배경/필요성** | 과도한 권한 부여는 내부자 위협·계정 탈취 시 피해를 확대하며, 부정 행위 방지를 위해 상호 견제 구조가 필수임 |
| **출제 의도** | 두 원칙의 상호 보완 관계와 IAM 구현 방안을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 최소권한  | --> | 직무분리  | --> | 상호견제  |
| (PoLP)   |     | (SoD)    |     | (Check)  |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 최소 권한(PoLP) | 업무 수행에 꼭 필요한 권한만 부여하고 나머지는 차단함 | 직원에게 해당 층 열쇠만 지급 |
| 정적 SoD | 상충하는 역할(발주·승인)을 동일인에게 동시 할당하지 않음 | 출납원과 감사원 분리 |
| 동적 SoD | 동일인이 상충 역할을 가져도 동일 트랜잭션에서 양쪽을 수행하지 못하게 제한함 | 같은 건에 대해 작성·승인 동시 금지 |

> 요약: 최소 권한(부여 최소화) + SoD(역할 분리)로 권한 남용과 부정 행위를 이중 방어함.

## Ⅲ. 절차
```
+------------+     +------------+
| 직무분석   | --> | 권한매핑   |
| (업무정의) |     | (최소부여) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 위반탐지   | <-- | SoD규칙   |
| 시정조치   |     | 적용      |
+------------+     +------------+
```

1. 직무 분석: 업무 프로세스를 분석하여 각 역할에 필요한 최소 권한을 정의함
2. 최소 권한 부여: 역할별로 필요한 권한만 매핑하고, 불필요한 기존 권한을 회수함
3. SoD 규칙 적용: 상충 역할 조합(발주-승인, 개발-배포 등)을 정의하고 동시 할당을 차단함
4. 위반 탐지·시정: 정기 감사에서 SoD 위반·과도 권한을 탐지하고 즉시 시정 조치함

> 요약: 직무 분석 → 최소 부여 → SoD 적용 → 위반 탐지로 권한 통제를 체계화함.

## Ⅳ. 문제점
- 권한 누적: 부서 이동·프로젝트 종료 후 이전 권한이 회수되지 않아 권한이 누적됨
- SoD 예외 남발: 인력 부족을 이유로 SoD 예외 승인이 빈발하여 원칙이 형해화됨
- 자동화 부족: 수동 권한 관리 시 누락·지연으로 실효성이 저하됨

## Ⅴ. 개선방안
- (단기) 정기 접근 리뷰: 분기별 Access Certification으로 불필요 권한을 식별·회수함
- (중기) IGA 자동화: Identity Governance로 입사·이동·퇴사 시 권한을 자동 프로비저닝·디프로비저닝함
- (장기) ZSP 전환: Zero Standing Privileges로 상시 권한을 제거하고 JIT 방식으로만 권한을 부여함

## Ⅵ. 전망
- 제로 트러스트 환경에서 최소 권한·SoD가 모든 접근 정책의 기본 원칙으로 강화되며, JIT 접근과 결합하여 상시 권한 자체를 제거하는 ZSP가 차세대 표준이 될 전망임
