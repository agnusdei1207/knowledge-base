## 미리 알고가기

- Root는 리눅스의 최고 권한 사용자임
- Rootless는 컨테이너 엔진과 컨테이너를 호스트의 일반 사용자 권한으로 실행하는 방식임
- 사용자 네임스페이스는 컨테이너 내부 ID와 호스트 ID를 다르게 매핑하는 기능임

## Ⅰ. 개요

- **정의/개념**: Rootless 컨테이너 보안은 컨테이너 엔진과 워크로드를 호스트 Root 권한 없이 실행해 호스트 장악 가능성을 줄이는 실행 방식임
- **배경/필요성**: 기본 컨테이너 운영은 엔진이나 워크로드가 강한 권한을 갖기 쉬움. 컨테이너 탈출 피해를 줄이려면 시작 권한을 낮춰야 함

## Ⅱ. 특징

- 컨테이너 내부에서 보이는 Root 권한을 호스트의 비특권 사용자로 매핑함
- 컨테이너 탈출이 일어나도 호스트에서 얻는 권한이 제한됨
- 개발 환경과 공유 서버처럼 호스트 보호가 중요한 곳에서 효과가 큼
- 일부 네트워크·스토리지 기능은 제약이 있어 호환성 검토가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Rootful 컨테이너 | Rootless 컨테이너 |
|:---|:---|:---|
| 호스트 권한 | 엔진과 워크로드가 강한 권한을 쓰기 쉬움 | 일반 사용자 권한 중심으로 동작함 |
| 침해 시 피해 범위 | 호스트 권한 탈취 위험이 큼 | 호스트 장악 범위를 크게 줄임 |
| 기능 호환성 | 기능 제약이 적음 | 일부 기능은 별도 우회나 설정이 필요함 |
| 적합 환경 | 성능과 호환성이 우선인 환경 | 보안 격리가 더 중요한 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 네임스페이스 | 컨테이너 내부 Root를 호스트의 비특권 ID로 매핑함 |
| Rootless 엔진 | Podman, Rootless Docker처럼 일반 사용자 권한으로 동작하는 엔진 계층임 |
| 비특권 네트워킹 | 사용자 공간 네트워크를 써서 낮은 권한으로 통신을 처리함 |
| 저장소 계층 | 호스트 파일 권한을 지키면서 이미지와 컨테이너 데이터를 관리함 |

```text
일반 사용자 -> Rootless 엔진 실행 -> 사용자 네임스페이스 매핑 -> 컨테이너 내부 Root 표시 -> 호스트에서는 비특권 권한 유지
```

## Ⅴ. 원리 및 절차 흐름도

```text
사용자 실행 요청 -> 사용자 네임스페이스 생성 -> ID 매핑 적용 -> 컨테이너 기동 -> 호스트 비특권 상태 유지
```

1. **실행 요청**: 일반 사용자가 컨테이너 실행을 요청함
2. **네임스페이스 생성**: 런타임이 사용자 네임스페이스를 만듦
3. **ID 매핑 적용**: 컨테이너 내부 Root를 호스트의 비특권 ID로 연결함
4. **컨테이너 기동**: 애플리케이션은 내부에서 필요한 사용자로 동작함
5. **격리 유지**: 호스트에서는 낮은 권한만 유지되어 피해 범위를 줄임

## Ⅵ. 실무 적용 및 유의점

1. 개발 서버와 공용 배치 서버는 Rootless 실행으로 호스트 장악 위험을 낮추고 Root 권한 컨테이너 수와 Root 노출 경로 수로 확인함
2. 저수준 포트나 특수 스토리지는 제약이 있으므로 대상 워크로드를 먼저 점검하고 기능 미지원 건수와 우회 설정 누적 수로 점검함

## Ⅶ. 결론

- Rootless 컨테이너는 침해를 완전히 없애는 기술이 아니라 침해 뒤 호스트 피해 범위를 크게 줄이는 기술이므로 권한 축소와 호환성 검토를 함께 봐야 함
