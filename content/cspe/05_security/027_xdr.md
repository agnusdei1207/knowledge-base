## Ⅰ. 개요
- **정의**: 엔드포인트·네트워크·클라우드·이메일 등 다계층 텔레메트리를 통합 분석하여 위협을 탐지·대응하는 플랫폼임
- **배경/필요성**: EDR(030 참조)·NDR(026 참조) 등 개별 솔루션의 사일로화로 공격 전체 경로를 파악하기 어려움
- **비유**: 각 층의 개별 CCTV를 통합 관제실에서 연결하여 건물 전체 동선을 추적하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SIEM·EDR 대비 XDR 차별점 | 다계층 상관분석·자동 대응 | XDR은 SIEM 대체가 아닌 보완 관계임을 명시 |

> 요약: 다계층 보안 텔레메트리를 상관분석하여 공격 전체 경로를 탐지·대응하는 통합 플랫폼임

## Ⅱ. 구성요소
```text
  Endpoint    Network    Cloud     Email
      |          |         |         |
      +-----+----+----+----+----+----+
            |              |
      [ Data Lake ]  [ Correlation Engine ]
            |              |
            +----- XDR Platform -----+
                       |
                  [ Response ]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Data Lake | 다계층 텔레메트리를 정규화·저장하는 중앙 데이터 저장소임 | 모든 CCTV 영상의 통합 저장소 |
| Correlation Engine | 서로 다른 소스의 이벤트를 상관분석하여 공격 체인을 재구성함 | 퍼즐 조각 맞추기 |
| Detection Model | ML·규칙 기반으로 다계층 이상 패턴을 탐지함 | 다각도 X-ray 판독 |
| Response Orchestrator | 탐지된 위협에 대해 격리·차단·티켓 생성 등 자동 대응을 수행함 | 자동 비상 대응 시스템 |

> 요약: 다계층 데이터를 수집·상관분석·탐지·자동 대응하는 통합 구조임

## Ⅲ. 절차
```text
텔레메트리 수집 --> 정규화/저장 --> 상관분석 --> 자동 대응
```
- 1단계: 엔드포인트·네트워크·클라우드·이메일에서 텔레메트리를 수집함
- 2단계: Data Lake에 정규화·인덱싱하여 통합 검색 가능 형태로 저장함
- 3단계: Correlation Engine이 MITRE ATT&CK 매핑 기반으로 공격 체인을 상관분석함
- 4단계: 위협 등급에 따라 자동 격리·차단·SOAR(029 참조) 플레이북 트리거를 수행함

> 요약: 다계층 텔레메트리를 수집·정규화한 후 상관분석으로 공격 체인을 탐지·대응함

## Ⅳ. 문제점
- 벤더 종속성: 단일 벤더 XDR은 타사 솔루션 연동이 제한되어 기존 투자 자산 활용이 어려움
- 데이터 과부하: 다계층 텔레메트리 대량 수집으로 저장·처리 비용이 급증함
- 탐지 모델 한계: 상관분석 규칙·ML 모델의 정확도가 환경별로 편차가 발생함

> 요약: 벤더 종속·데이터 과부하·모델 편차가 XDR의 주요 과제임

## Ⅴ. 개선방안
1. 단기: Open XDR(다벤더 연동) 아키텍처를 채택하여 벤더 종속성을 완화함
2. 중기: 텔레메트리 티어링(Hot/Warm/Cold) 전략으로 저장 비용을 최적화함
3. 장기: 환경별 ML 모델 파인튜닝과 피드백 루프를 구축하여 탐지 정확도를 향상함

> 요약: Open XDR, 데이터 티어링, 모델 튜닝으로 통합 탐지 체계를 고도화함

## Ⅵ. 전망
- 발전 방향: AI 기반 자율 위협 헌팅과 자동 대응이 XDR의 핵심 기능으로 확장됨
- 기술사적 판단: SOC 운영의 중심 플랫폼이 SIEM에서 XDR+SOAR 조합으로 이동하는 추세임
- 기술사 제언: XDR 도입 시 기존 SIEM·EDR·NDR과의 역할 분담 아키텍처 설계가 필요함
