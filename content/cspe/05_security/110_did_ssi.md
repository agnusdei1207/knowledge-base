## 미리 알고가기

- DID는 중앙 기관에 종속되지 않는 식별자와 공개키 문서 체계이고, SSI는 사용자가 자기 신원 정보를 더 많이 통제하는 신원 운영 철학임
- VC는 발급자가 서명한 자격증명이고, SSI 환경에서 DID와 함께 자주 쓰임
- 기술보다 중요한 쟁점은 키 복구와 상호운용성과 필요한 정보만 제시하는 프라이버시 설계임

## Ⅰ. 개요

- **정의/개념**: DID·SSI는 중앙 신원 제공자 의존 없이 사용자가 식별자와 자격증명을 보유·제시하고 필요한 범위만 검증자에게 제공하는 신원 체계임
- **배경/필요성**: 중앙 계정 체계는 플랫폼 종속, 과도한 개인정보 전달, 대규모 유출 위험이 큼. 사용자 통제권과 재사용성이 필요함

## Ⅱ. 특징

- 사용자가 지갑 형태로 자격증명을 직접 보관하고 제시할 수 있음
- 발급자와 검증자가 실시간 중앙 DB 조회 없이도 진위 검증이 가능함
- 필요한 속성만 선택적으로 제시할 수 있어 프라이버시 강화에 유리함
- 키 분실과 다양한 DID method 난립은 실제 도입의 큰 장애 요인임

## Ⅲ. 종류 및 비교

| 판단 기준 | 중앙 계정 기반 신원 | DID·SSI 기반 신원 |
|:---|:---|:---|
| 신원 제어권 | 서비스 제공자 중심 | 사용자/보유자 중심 |
| 데이터 제공 방식 | 전체 계정 정보 전달이 쉬움 | 필요한 속성만 제시 가능 |
| 검증 방식 | 중앙 서버 조회 중심 | 서명과 상태 정보 검증 중심 |
| 주요 과제 | 종속성과 대규모 유출 | 복구와 상호운용과 사용자 경험 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DID | 공개키와 연결되는 사용자 또는 조직 식별자임 |
| Wallet | 키와 자격증명을 저장하고 제출을 관리함 |
| Issuer / Holder / Verifier | 발급자, 보유자, 검증자 역할을 이룸 |
| VC / Presentation | 자격증명 발급과 선택적 제시를 담당함 |

```text
식별자 생성 -> 자격증명 발급 -> 지갑 보관 -> 필요한 정보만 제시 -> 검증자 확인
```

## Ⅴ. 원리 및 절차 흐름도

```text
DID 생성 -> 발급자 서명 -> VC 수령 -> VP 구성 -> 검증자 서명/상태 확인 -> 서비스 이용
```

1. **DID 생성**: 사용자나 조직이 식별자와 키를 생성함
2. **자격증명 발급**: 기관이 사실 정보를 서명해 VC를 만듦
3. **지갑 보관**: 보유자가 자격증명을 저장함
4. **선택 제시**: 검증 목적에 필요한 정보만 제시함
5. **검증과 이용**: 검증자가 발급자와 상태 정보를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 모바일 신분증·자격 증명은 복구 정책과 공통 프로파일을 설계하고 교차 서비스 검증 성공률과 복구 성공률로 확인함
2. SSI도 필요한 상태 검증 체계를 남기고 불필요 개인정보 제출 감소와 폐기·정지 상태 반영 정확도로 확인함

## Ⅶ. 결론

- DID·SSI는 신원 제어권을 사용자 쪽으로 옮기는 모델이지만 상호운용성과 복구와 상태 검증을 함께 설계해야 실무에서 작동함
