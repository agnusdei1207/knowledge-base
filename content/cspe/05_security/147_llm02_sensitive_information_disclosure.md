## 미리 알고가기

- 민감 정보는 개인정보, 인증 정보, 소스코드, 영업 비밀처럼 노출되면 피해가 큰 정보를 말함
- 검색 증강 생성은 사내 문서나 외부 문서를 찾아 답변에 함께 넣는 방식임
- 접근통제는 사용자가 볼 수 있는 문서와 도구 범위를 권한에 맞게 제한하는 절차임

## Ⅰ. 개요

- **정의/개념**: LLM02 민감 정보 노출은 모델이나 연결 애플리케이션이 대화, 학습 데이터, 검색 문서, 로그의 민감 정보를 응답으로 드러내는 위험 항목임
- **배경/필요성**: 생성형 AI 서비스는 대화 기록, 사내 문서, 도구를 함께 다룸. 기존 웹 정보 노출보다 유출 경로가 넓고 복구도 더 어려움

## Ⅱ. 특징

- 시스템 프롬프트 유출보다 범위가 넓어 개인정보, 비밀 키, 내부 문서까지 포함함
- 학습 데이터 암기, 대화 기록 재사용, 검색 증강 생성 권한 오류, 로그 노출이 함께 원인이 될 수 있음
- 한 번 모델 내부나 외부 기억 계층에 들어간 정보는 제거가 쉽지 않음
- 데이터 분류와 접근통제와 출력 검토를 같이 설계해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 프롬프트 유출 | LLM02 민감 정보 노출 |
|:---|:---|:---|
| 주된 대상 | 시스템 프롬프트와 내부 지침 | 개인정보, 인증 정보, 업무 기밀, 대화 내용 |
| 흔한 원인 | 숨은 지시 반사 출력 | 학습 암기, 권한 없는 검색, 로그·메모리 재사용 |
| 피해 성격 | 방어 우회와 공격 정교화 | 규제 위반, 직접적 기밀 유출 |
| 방어 초점 | 프롬프트 최소화와 비밀 분리 | 데이터 마스킹과 접근통제와 출력 검토 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 학습 데이터 | 민감 정보가 섞이면 모델 암기 위험이 생김 |
| 대화 메모리 | 이전 사용자 입력과 응답이 다시 노출될 수 있음 |
| 검색 문서 저장소 | 권한이 다른 문서를 찾아 오는 검색 증강 생성 원천임 |
| 권한 문맥 | 어떤 사용자가 무엇을 볼 수 있는지 결정함 |
| 출력 필터 | 응답에 민감 정보가 포함됐는지 마지막에 검사함 |

```text
사용자 질의 -> 메모리/문서 검색 -> 모델 응답 생성 -> 출력 필터 -> 사용자
```

## Ⅴ. 원리 및 절차 흐름도

```text
민감 정보 유입 -> 저장 또는 학습 -> 권한 검증 실패 또는 암기 재현 -> 응답 생성 -> 정보 노출
```

1. **민감 정보 유입**: 사용자가 비밀 값이나 기밀 문서를 입력하거나 연결함
2. **저장 또는 학습**: 정보가 로그, 메모리, 검색 저장소, 학습 데이터에 남음
3. **권한 검증 실패**: 검색 단계나 응답 단계에서 접근 범위를 제대로 따지지 못함
4. **응답 생성**: 모델이 민감한 내용을 그대로 또는 요약해 출력함
5. **정보 노출**: 사용자나 외부 공격자에게 기밀이 전달됨

## Ⅵ. 실무 적용 및 유의점

1. 사내 문서 챗봇은 문서별 권한을 검색 단계에서 반영하고 비밀 값을 마스킹하며 무권한 검색 건수와 유출 재현 성공률로 점검함
2. 퍼블릭 LLM 업무 사용은 대화 기록 재학습 범위와 로그 보관 정책을 정하고 비식별 처리 누락 건수와 민감정보 차단률로 확인함

## Ⅶ. 결론

- LLM02는 모델이 친절하게 답하는 과정 자체가 유출 경로가 되는 문제이므로 데이터 통제와 출력 통제를 동시에 설계해야 함
