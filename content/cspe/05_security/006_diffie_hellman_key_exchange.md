## 미리 알고가기

- 이산대수 문제: $g^a mod p$에서 $a$를 찾기 어렵다는 수학적 난제임
- 공유 비밀: 양측이 각자 계산해 같은 값으로 도달하는 키 재료임
- 임시 키: 세션마다 새로 생성하고 폐기하는 키임
- MITM: 공격자가 양측 사이에서 각각 다른 키 교환을 맺는 공격임
- ECDHE: 타원곡선 기반 임시 DH 키 교환 방식임

## Ⅰ. 개요

- **정의/개념**: 디피-헬만 키 교환은 공개 채널에서 각자의 비밀값과 상대 공개값으로 같은 공유 비밀을 계산하는 절차임
- **배경/필요성**: 대칭키 암호를 쓰려면 양측이 같은 키를 가져야 함. 키 자체를 보내지 않는 합의 절차가 필요함

## Ⅱ. 특징

- 통신로에 공개값이 노출되어도 비밀 지수는 직접 전송하지 않음
- 인증 없는 DH는 중간자 공격을 막지 못함
- 임시 DH를 쓰면 세션 종료 후 과거 키 재계산 가능성을 낮출 수 있음
- 안전성은 그룹 선택, 난수 품질, 공개값 검증에 영향을 받음

## Ⅲ. 종류 및 비교

| 구분 | 정적 DH | DHE | ECDHE |
|:---|:---|:---|:---|
| 키 사용 | 장기 DH 키 | 세션별 임시 키 | 세션별 타원곡선 임시 키 |
| PFS | 제한적 | 제공 가능 | 제공 가능 |
| 연산 기반 | 유한체 이산대수 | 유한체 이산대수 | 타원곡선 이산대수 |
| 적용 판단 | 레거시 호환 | 표준 그룹 관리 필요 | TLS에서 일반적 선택 |

> 요약: DH의 선택 기준은 키를 직접 보내지 않는다는 사실보다 인증 결합과 임시 키 사용 여부임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 공개 매개변수 | 양측이 공유하는 그룹과 생성자 |
| 개인 지수 | 각 참여자가 외부에 공개하지 않는 난수 |
| 공개값 | 상대에게 보내는 계산 결과 |
| 공유 비밀 | 양측이 독립 계산으로 얻는 같은 값 |
| KDF | 공유 비밀을 세션키로 변환 |

```text
Alice: a, g^a  ---- g^a ----> Bob
Alice: (g^b)^a <--- g^b ----  Bob: b, g^b
양측 공유 비밀: g^(ab)
```

## Ⅴ. 원리 및 절차 흐름도

1. **매개변수 합의**: 사용할 그룹과 생성자를 정함
2. **개인값 생성**: 각자 난수 개인 지수를 생성함
3. **공개값 교환**: 개인값에서 계산한 공개값을 상대에게 보냄
4. **공유 비밀 계산**: 상대 공개값과 자신의 개인값으로 같은 값을 계산함
5. **키 도출**: KDF로 암호화 키와 인증 키를 분리함

## Ⅵ. 실무 적용 및 유의점

- TLS에서는 인증서 서명으로 DH 공개값 교환 상대를 확인함
- 공개값 범위와 작은 부분군 공격 가능성을 검증해야 함
- 재사용 임시 키는 PFS 성질을 약화시키므로 세션 단위 생성·폐기가 필요함
- 취약한 소수 그룹이나 짧은 키 길이는 정책에서 제외함
- PQC 전환기에는 ECDHE와 ML-KEM 결합 방식을 검토함

## Ⅶ. 결론

- DH는 대칭키 자체를 보내지 않고 공유 키 재료를 합의하는 절차임
- 답안에서는 “안전한 키 교환”이라고 쓰기보다 인증, 그룹 검증, 임시 키 사용을 함께 써야 함

## 작성 근거(검토용)

- DH의 문맥상 판단 단어는 결과가 아니라 키 합의 절차와 인증 결합임
- MITM 한계를 명시해 “공개 채널에서 안전”이라는 과잉 단정을 제거함
- TLS, PQC 하이브리드와 이어지는 실무 판단 축을 남김
