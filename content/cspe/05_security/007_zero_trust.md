## Ⅰ. 개요
- **정의**: 네트워크 위치와 무관하게 모든 접근 요청을 신뢰하지 않고 지속 검증하는 보안 원칙
- **배경/필요성**: 클라우드·원격근무 확산으로 내부/외부 경계가 무의미해져 경계 기반 보안 모델의 한계가 드러남
- **비유**: 사내 직원이라도 매번 신분증을 확인하고 방문 목적을 검증하는 보안 정책과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 제로트러스트 원칙과 경계 보안과의 차이 | 지속 검증·최소 권한·침해 가정 3대 원칙 | 제로트러스트를 특정 제품으로 설명하지 않을 것 |

> 요약: 제로트러스트는 "신뢰하지 않고 검증"을 기본 전제로 하는 보안 패러다임임

## Ⅱ. 구성요소
```text
+----------+   요청   +---------+   검증   +---------+
| 주체     |-------->| 정책엔진|-------->| 자원    |
| (사용자/ |         | (PDP/   |         | (앱/    |
|  디바이스)|         |  PEP)   |         |  데이터)|
+----------+         +---------+         +---------+
                        |
                        v
                 [컨텍스트 수집]
              (ID/디바이스/위치/행위)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 지속 검증 | 매 접근 요청마다 주체·디바이스·컨텍스트를 재검증함 | 매번 출입증 + 방문 사유 확인 |
| 최소 권한 | 업무 수행에 필요한 최소 범위만 한시적으로 부여함 | 필요한 방만 열리는 카드키 |
| 마이크로 세그먼테이션 | 네트워크를 세분화하여 측면 이동(Lateral Movement)을 차단함 | 칸막이로 구역별 격리 |

> 요약: 지속 검증·최소 권한·마이크로 세그먼테이션이 제로트러스트의 3대 핵심 요소임

## Ⅲ. 절차
```text
접근요청 --> 컨텍스트수집 --> 정책평가 --> 동적허용/거부
```
- 1단계: **접근요청** — 주체가 자원 접근을 요청하면 PEP가 가로챔
- 2단계: **컨텍스트수집** — 사용자 ID·디바이스 상태·위치·시간·행위 패턴을 수집함
- 3단계: **정책평가** — PDP가 수집된 컨텍스트를 기반으로 접근 정책을 실시간 평가함
- 4단계: **동적허용/거부** — 평가 결과에 따라 접근을 허용·제한·차단하고 로깅함

> 요약: 매 접근 시 컨텍스트를 수집·평가하여 동적으로 접근을 결정하는 것이 핵심임

## Ⅳ. 문제점
- 구축 복잡도: 기존 레거시 시스템에 지속 검증 체계를 적용하기 어려움
- 사용자 경험 저하: 잦은 인증·검증으로 업무 생산성이 감소할 수 있음
- 가시성 부족: 모든 자산·트래픽을 식별·분류하지 못하면 정책 적용에 공백이 발생함

> 요약: 구축 복잡도·UX 저하·자산 가시성 부족이 제로트러스트 도입의 주요 장벽임

## Ⅴ. 개선방안
1. 단기: 고위험 자산부터 단계적으로 적용하여 구축 복잡도를 분산함
2. 중기: 적응형 인증(Risk-Based AuthN)으로 저위험 접근의 인증 부담을 경감함
3. 장기: 자산 자동 탐색·분류 체계를 구축하여 전체 가시성을 확보함

> 요약: 단계적 적용·적응형 인증·자산 가시성 확보로 도입 장벽을 완화함

## Ⅵ. 전망
- 발전 방향: NIST SP 800-207 기반 제로트러스트 아키텍처(008 참조)가 공공·민간에 확산됨
- 기술사적 판단: 제로트러스트는 보안 패러다임 전환의 핵심이며 SASE(009 참조)·SSE(010 참조)와 융합됨
- 기술사 제언: 제로트러스트 성숙도 모델 기반 로드맵을 수립하고 단계별 이행을 권고함
