# 📖 【암기용】 개념 완전 이해

> 목적: 보안 코드 리뷰를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 소스코드에서 취약한 구현과 설계 누락을 배포 전 식별하는 활동
- **왜 필요한가**: SAST·DAST가 찾는 패턴형 취약점만으로는 인증 우회, 권한 검증 누락, 비즈니스 로직 결함을 충분히 포착하기 어렵다.
- **핵심 직관**: 코드를 범죄 현장처럼 보는 것이 아니라, 데이터가 어디서 들어와 어떤 권한으로 저장·출력되는지 추적하는 점검이다.

## 깊이 이해
- **배경·문제의식**: CI/CD 배포 주기가 짧아지면서 출시 후 침투테스트만으로는 OWASP Top 10·CWE Top 25 결함을 제때 줄이기 어렵다. 코드 리뷰 단계에서 입력 검증, 인증·인가, 암호화, 로깅 누락을 잡아야 결함 수정 비용을 낮출 수 있다.
- **작동 원리**: PR 변경분을 중심으로 자동 도구(SAST, Secret Scan, Dependency Scan) 결과를 먼저 확인하고, 사람이 고위험 모듈의 데이터 흐름과 권한 경계를 추적한다. OWASP ASVS, CWE, 조직 보안 코딩 표준을 체크리스트로 삼는다.
- **비유**: 건물 준공 전 전기 배선과 비상구를 확인하는 감리와 같다. 자동 장비가 누전 위치를 찾고, 전문가는 사람들이 실제로 이동하는 경로와 잠금 장치를 확인한다.
- **구체 예시**: 결제 API PR에서 `amount`를 클라이언트 입력 그대로 승인하면 SAST는 단순 할당으로 볼 수 있으나, 리뷰어는 서버 측 주문 금액 재계산 누락을 비즈니스 로직 취약점으로 표시한다.
- **흔한 오해·주의점**: 보안 코드 리뷰는 개발자 코드 스타일 지적이 아니다. 보안 요구사항, 데이터 흐름, 권한 검증, 취약점 재현 가능성을 근거로 결함을 판정해야 한다.

## 연결 개념
- OWASP ASVS — 인증·세션·입력검증 등 애플리케이션 보안 요구사항 기준
- CWE — 취약한 코드 패턴의 표준 분류 체계
- DevSecOps — PR·CI 파이프라인에 보안 검토를 삽입하는 운영 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 도구 목록 나열이 아니라, 사람이 검토할 영역과 자동 도구가 검출할 영역을 분리해 결함 제거율과 리뷰 시간을 통제한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 보안 코드 리뷰는 배포 전 소스코드 변경분에서 취약 구현, 권한 검증 누락, 비즈니스 로직 결함을 식별하는 예방 통제이다.
> 2. **가치**: OWASP ASVS·CWE·Secure Coding Standard 기반 PR 검토로 출시 후 취약점 수정 비용과 긴급 패치 건수를 낮춘다.
> 3. **판단 포인트**: 자동 도구는 패턴형 결함, 수동 리뷰는 인증·인가·업무 규칙·데이터 흐름 결함에 배치해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SDLC 보안 통제 설계 역량 확인 | PR 리뷰, SAST, Secret Scan, OWASP ASVS, CWE 매핑 | 도구명만 나열하고 수동 검토 범위를 누락 |
| 고위험 코드 선별 판단 확인 | 인증·인가·결제·파일업로드·암호화·외부 API 우선순위 | 전체 코드 100% 수동 검토를 현실 방안처럼 제시 |
| 결함 추적과 개선 지표 확인 | 발견 결함, false positive, MTTR, 재발률 | 리뷰 결과가 배포 승인 기준과 연결되지 않음 |

> 요약: 이 문제는 보안 코드 리뷰를 개발 프로세스 통제가 아닌 취약점 예방·검증 체계로 설계하는 역량을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 배포 전 코드 변경분 보안 검토
- 배경: 애플리케이션 취약점은 입력값 처리, 권한 검증, 암호화 사용, 로그 마스킹 누락에서 반복 발생하고 자동 도구는 비즈니스 로직 결함을 놓칠 수 있음
- 필요성: OWASP ASVS·CWE 기준으로 PR 자동 검사와 고위험 모듈 수동 검토를 결합하고 Critical 0건, High 7일 SLA, PR 리뷰 p95 24시간 이하를 지표로 삼아야 함

---

## Ⅱ. 구조 및 구성요소

```text
요구사항/PR -> 자동 점검(SAST/Secret/Dependency)
           -> 수동 리뷰(데이터 흐름/권한/로직)
           -> CWE/ASVS 매핑 -> 결함 조치 -> 승인/차단
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| PR 변경분 | 리뷰 대상 범위 한정 | diff, 신규 API, 권한 변경 우선 |
| 자동 도구 | 패턴형 결함·비밀정보·취약 라이브러리 탐지 | SAST, SCA, Secret Scan |
| 수동 리뷰 | 업무 로직·권한 경계·데이터 흐름 검증 | 인증·인가·결제·관리자 기능 |
| 기준 체계 | 결함 판정 기준 제공 | OWASP ASVS, CWE, 내부 보안 코딩 표준 |

> 요약: 구조는 변경분을 자동 도구로 1차 선별하고, 수동 리뷰가 고위험 흐름을 검증한 뒤 표준 기준으로 조치하는 체계이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
PR 생성 -> 위험도 분류 -> 자동 스캔
       -> 리뷰어 할당 -> 체크리스트 검토
       -> 결함 등록/수정 -> 재검증 -> merge 승인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 변경 파일·API·권한 변경 식별 | 인증·인가·외부입력 포함 여부 |
| 2 | SAST/SCA/Secret Scan 실행 | Critical 0건, High 예외 승인 |
| 3 | 리뷰어가 데이터 흐름과 권한 경계 추적 | ASVS V1~V14, CWE 매핑 |
| 4 | 결함 수정 후 재검토 | 재현 절차, 단위/통합 테스트 |
| 5 | 승인·차단·예외 기록 | PR 승인자, 근거, 만료일 |

> 요약: 흐름은 위험도 분류 후 자동 탐지와 수동 판단을 결합하고, 수정·재검증 근거가 남을 때 병합을 승인한다.

## Ⅳ. 특징

| 구분 | 기존 일반 코드 리뷰 | 보안 코드 리뷰 | 수치·기준 |
|:---|:---|:---|:---|
| 초점 | 가독성·유지보수 | 취약점·권한·데이터 노출 | OWASP Top 10, CWE Top 25 |
| 검토 방식 | 개발자 상호 검토 | 도구+보안 리뷰어 병행 | Critical 0건, High SLA 7일 |
| 대상 선별 | 전체 변경분 균등 검토 | 고위험 모듈 우선 | 인증·결제·관리자·파일 업로드 |
| 산출물 | 코멘트·승인 | 결함 티켓·위험 수용 기록 | CVSS, ASVS control ID |

> 요약: 보안 코드 리뷰는 코드 품질 코멘트보다 취약점 재현 가능성, 표준 매핑, 배포 승인 기준을 중점으로 삼는다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 검출 범위 | SAST 단독은 패턴 중심 | 수동+도구 결합으로 로직 결함 포함 | 인증·인가 결함 비중이 높은 서비스 |
| 비용/시간 | 전체 수동 리뷰는 일정 지연 | 위험 기반 샘플링·체크리스트 | PR당 30~60분 리뷰 제한 |
| 운영/위험 | 사후 침투테스트 의존 | PR 단계 결함 차단 | 배포 빈도 일 1회 이상 |

> 요약: 배포 빈도가 높고 권한·결제 로직이 많은 서비스는 자동 도구와 고위험 수동 리뷰를 결합해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| False Positive 누적 | SAST 규칙 과다 | CWE별 suppression 승인·만료일 관리 | false positive rate 30% 이하 |
| 로직 결함 누락 | 도구가 업무 규칙 미인지 | abuse case, 권한 매트릭스 리뷰 | 권한 우회 결함 0건 |
| 리뷰 병목 | 보안팀 승인 집중 | 보안 챔피언, checklist self-review | PR 대기시간 p95 24시간 이하 |

> 요약: 주요 리스크는 도구 노이즈, 로직 결함 누락, 승인 병목이며 규칙 튜닝과 역할 분산으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 결함 차단 | Critical 0건, High 7일 내 조치 | SAST/SCA 리포트, Jira 티켓 |
| 리뷰 품질 | CWE·ASVS 매핑률 90% 이상 | 리뷰 체크리스트 표본 감사 |
| 운영 지표 | PR 리뷰 p95 24시간 이하 | Git 플랫폼 webhook, 대시보드 |

> 요약: 도입 성과는 결함 심각도, 표준 매핑률, PR 대기시간을 함께 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. PR 템플릿에 인증·인가·입력검증·암호화·로그 마스킹 체크리스트를 넣고 OWASP ASVS V1~V14 항목으로 매핑함
2. CI에 SAST, SCA, Secret Scan을 배치하고 Critical 0건, High 7일 SLA, 예외 만료일 30일 기준을 적용함
3. 고위험 모듈(결제, 관리자, 파일 업로드, 외부 API)은 보안 리뷰어 1인과 도메인 개발자 1인이 공동 승인함

**결론 (2줄):**
- 기술사 판단: 일반 CRUD는 자동 도구 중심, 인증·결제·관리자 기능은 수동 리뷰를 필수 게이트로 둔다
- 향후 방향: AI 코드 생성 확대에 따라 생성 코드의 CWE 매핑, 비밀정보 탐지, 라이선스 검토를 PR 단계에 통합한다
