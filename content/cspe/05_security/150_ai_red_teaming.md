## 미리 알고가기

- 레드팀은 공격자 관점에서 취약점을 찾아 내는 검증 활동임
- 벤치마크 평가는 정해진 문제 세트로 성능을 재는 방식이고 실제 악용 가능성까지는 다 보지 못함
- 완화 조치는 발견된 위험을 줄이기 위해 프롬프트, 권한, 필터, 운영 절차를 고치는 작업임

## Ⅰ. 개요

- **정의/개념**: AI 레드팀은 모델, 프롬프트, 검색, 도구 호출, 운영 절차를 공격자 시각에서 시험해 안전성과 오남용 위험을 찾는 적대적 평가 활동임
- **배경/필요성**: 정확도와 일반 품질 시험만으로는 프롬프트 인젝션, 정보 유출, 유해 응답, 권한 오남용 같은 운영 위험을 놓치기 쉬움

## Ⅱ. 특징

- 모델 하나가 아니라 서비스 전체 파이프라인을 함께 봄
- 자동 테스트와 사람 주도 시험을 함께 돌려 빈틈을 줄임
- 단발성 평가보다 수정 뒤 재시험까지 포함해야 의미가 있음
- 보안뿐 아니라 안전, 편향, 오남용, 규제 위험까지 같이 다룰 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 침투 테스트 | AI 레드팀 |
|:---|:---|:---|
| 주된 대상 | 네트워크, 웹, 인프라 취약점 | 모델 응답, 프롬프트, 검색, 도구 호출 |
| 시험 방식 | 취약한 포트와 코드 결함을 노림 | 우회 질문, 유출 유도, 도구 오남용을 노림 |
| 결과 형태 | 서버 침해와 권한 탈취 확인 | 유해 응답, 정보 유출, 승인 없는 실행 확인 |
| 후속 조치 | 패치와 설정 수정 | 프롬프트, 권한, 필터, 운영 절차 보완 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 평가 범위 | 모델, 프롬프트, 검색 증강 생성, 도구, 로그까지 어디를 볼지 정함 |
| 공격 시나리오 | 탈옥, 유출, 과도 권한, 비용 공격 같은 시험 항목임 |
| 시험자와 도구 | 사람 주도 공격과 자동 재현 도구를 함께 씀 |
| 판정 기준 | 심각도, 재현성, 피해 범위로 결과를 분류함 |
| 보완 백로그 | 수정 우선순위를 정하고 재시험 일정을 묶음 |

```text
범위 정의 -> 공격 시나리오 작성 -> 시험 실행 -> 결과 분류 -> 보완 -> 재시험
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 자산 식별 -> 적대적 질문과 입력 설계 -> 응답과 실행 결과 수집 -> 심각도 평가 -> 수정 뒤 재검증
```

1. **자산 식별**: 어떤 모델과 도구와 문서 저장소가 위험한지 정함
2. **입력 설계**: 우회 질문, 유출 질문, 악성 문서를 준비함
3. **시험 실행**: 실제 서비스에 넣어 응답과 실행 결과를 모음
4. **심각도 평가**: 재현성과 피해 크기로 우선순위를 정함
5. **재검증**: 수정 뒤 같은 시나리오를 다시 돌려 개선 여부를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 배포 전 AI 서비스는 프롬프트, 검색, 도구 호출까지 포함한 레드팀을 거치고 재현된 치명 취약점 수와 조치 완료율로 확인함
2. 모델, 프롬프트, 플러그인이 자주 바뀌는 서비스는 큰 변경 뒤 같은 시나리오를 다시 돌리고 재개방 취약점 수로 점검함

## Ⅶ. 결론

- AI 레드팀은 모델 품질 시험의 보조가 아니라 실제 운영 위험을 드러내는 본시험이므로 수정과 재시험까지 묶어 운영해야 함
