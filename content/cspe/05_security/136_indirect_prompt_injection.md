## 미리 알고가기

- 검색 증강 생성은 외부 문서를 찾아 함께 넣어 답하는 방식이며 보통 RAG라고 부름
- 시스템 프롬프트는 서비스가 모델에 미리 주는 역할과 금지 규칙임
- 도구 호출은 모델이 검색, 메일 전송, 파일 수정 같은 외부 기능을 실행하는 구조임

## Ⅰ. 개요

- **정의/개념**: 간접 프롬프트 인젝션은 웹페이지, 문서, 메일처럼 모델이 참고하는 외부 콘텐츠 안에 숨긴 지시로 시스템 프롬프트를 흔들고 잘못된 응답이나 도구 실행을 유도하는 공격임
- **배경/필요성**: 검색 증강 생성과 브라우징 기능이 늘면서 모델은 신뢰하지 않는 문서를 데이터와 명령의 경계 없이 함께 읽게 되었고, 이 경계 붕괴가 새로운 공격면이 됨

## Ⅱ. 특징

- 사용자가 공격 문장을 직접 치지 않아도 외부 문서만으로 공격이 성립할 수 있음
- 정상 문서처럼 보이는 본문, 주석, 숨은 텍스트에 지시를 심을 수 있음
- 잘못된 답변에 그치지 않고 고권한 도구 호출과 정보 유출로 이어질 수 있음
- 금칙어 필터만으로는 막기 어려워 입력 분리와 권한 통제가 함께 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 |
|:---|:---|:---|
| 공격 위치 | 사용자가 대화창에 지시를 직접 넣음 | 외부 문서나 웹페이지에 지시를 숨김 |
| 사용자가 알아차리기 | 비교적 쉬움 | 문서를 읽는 과정에서 몰래 섞이기 쉬움 |
| 자주 생기는 환경 | 일반 챗봇, 테스트 우회 | 검색 증강 생성, 브라우저 에이전트, 메일 요약 |
| 방어 초점 | 시스템 지침 보호와 출력 제어 | 외부 콘텐츠 분리와 도구 권한 축소 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 질의 | 검색과 요약을 유발하는 시작 입력임 |
| 검색기·브라우저 | 외부 웹페이지와 문서를 가져오는 연결 지점임 |
| 외부 콘텐츠 | 숨은 지시가 섞일 수 있는 비신뢰 입력 원천임 |
| 모델 해석 계층 | 시스템 지침과 외부 문장을 함께 읽고 우선순위를 판단함 |
| 정책·권한 계층 | 응답 검토와 도구 실행 허용 범위를 마지막에 제한함 |

```text
사용자 질의 -> 검색기/브라우저 -> 외부 콘텐츠 수집
                                 |
시스템 프롬프트 ------------------+-> 모델 해석 -> 응답/도구 호출 -> 정책 검토
```

## Ⅴ. 원리 및 절차 흐름도

```text
외부 문서 수집 -> 숨은 지시 유입 -> 모델이 지시를 혼동 -> 응답 왜곡 또는 도구 호출 -> 출력 차단 또는 기록
```

1. **외부 문서 수집**: 모델이 검색 결과나 첨부 문서를 읽음
2. **숨은 지시 유입**: 문서 안의 공격 문장이 시스템 지침과 함께 전달됨
3. **지시 혼동**: 모델이 외부 문장을 데이터가 아니라 명령처럼 받아들임
4. **위험 행동 발생**: 잘못된 답을 하거나 도구를 과하게 실행함
5. **차단과 기록**: 정책 검사와 승인 절차가 있으면 피해를 줄일 수 있음

## Ⅵ. 실무 적용 및 유의점

1. 메일 요약과 웹 검색을 붙인 에이전트는 외부 문서를 신뢰 입력과 분리하고 고위험 도구는 승인 뒤에만 실행되게 해야 하며 차단된 도구 호출 수와 우회 재현 성공률로 점검함
2. 검색 증강 생성에서 원문을 통째로 넣으면 숨은 지시가 그대로 들어오므로 문서 정화와 인용 범위 제한을 적용하고 악성 문서 테스트 통과율과 민감정보 유출 건수로 확인함

## Ⅶ. 결론

- 간접 프롬프트 인젝션은 외부 문서를 데이터로만 다루지 못할 때 생기므로 입력 분리와 도구 권한 축소가 핵심 방어축임
