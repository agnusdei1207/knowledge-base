## 미리 알고가기

- 시스템 프롬프트는 모델의 역할, 금지 규칙, 응답 형식을 담은 내부 지침임
- 숨은 지시는 사용자에게 보이지 않지만 서비스 내부에서 모델에 함께 전달되는 문장임
- 출력 필터는 모델 답변을 다시 검사해 비밀 정보나 위험 문장을 막는 계층임

## Ⅰ. 개요

- **정의/개념**: 프롬프트 유출은 모델이 내부 시스템 프롬프트, 운영 규칙, 숨은 지시를 답변 속에 드러내거나 재구성하는 노출 문제임
- **배경/필요성**: 시스템 프롬프트에는 정책 문구, 도구 이름, 내부 절차가 들어갈 수 있음. 이 지침이 새면 방어 우회와 후속 공격이 쉬워짐

## Ⅱ. 특징

- 일반 데이터 유출과 달리 모델을 제어하는 숨은 규칙이 노출된다는 점이 핵심임
- 한 번 새어 나온 지침은 이후 탈옥과 인젝션 공격 재료가 됨
- 디버그 응답, 과도한 자기 설명, 장문 인용 과정에서 자주 드러남
- 비밀 값을 프롬프트 안에 직접 넣어 두면 설계 단계부터 취약해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 프롬프트 유출 | 민감 정보 노출 |
|:---|:---|:---|
| 주된 대상 | 시스템 프롬프트와 내부 지침 | 개인정보, 업무 문서, 자격 증명 |
| 흔한 원인 | 숨은 지시 반사 출력, 디버그 응답 | 학습 데이터 암기, 권한 우회, 검색 증강 생성 오설계 |
| 후속 위험 | 탈옥과 정책 우회가 쉬워짐 | 기밀 유출과 규제 위반이 발생함 |
| 방어 초점 | 프롬프트 최소화와 비밀 분리 | 데이터 분류와 접근통제 강화 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시스템 프롬프트 | 역할과 정책을 담지만 새면 공격 힌트가 됨 |
| 사용자 질의 | 내부 지침을 캐내는 탐색 질문이 들어오는 창구임 |
| 컨텍스트 메모리 | 이전 대화와 운영 지침이 함께 쌓이는 공간임 |
| 모델 응답 | 숨은 문장을 요약하거나 복사해 노출할 수 있음 |
| 출력 통제 | 내부 지침과 유사한 답변을 마지막에 막는 계층임 |

```text
시스템 프롬프트 + 대화 기록 + 사용자 질의 -> 모델 응답 생성 -> 출력 통제 -> 사용자
```

## Ⅴ. 원리 및 절차 흐름도

```text
탐색 질문 입력 -> 모델이 내부 지침 참조 -> 숨은 문장 재구성 -> 답변에 노출 -> 후속 우회 공격에 활용
```

1. **탐색 질문 입력**: 공격자가 규칙, 금지 목록, 초기 지시를 묻는 질문을 던짐
2. **내부 지침 참조**: 모델이 답을 만들며 시스템 프롬프트를 함께 읽음
3. **문장 재구성**: 내부 문구를 그대로 또는 비슷하게 풀어 씀
4. **노출 발생**: 운영 규칙과 내부 절차가 사용자에게 드러남
5. **후속 악용**: 노출된 문구를 바탕으로 탈옥이나 우회 입력을 정교화함

## Ⅵ. 실무 적용 및 유의점

1. 시스템 프롬프트에 API 키나 내부 주소를 넣지 말고 비밀 저장소로 분리하며 유출 재현 성공률과 프롬프트 일치 문장 수로 점검함
2. 고객지원 챗봇과 사내 비서는 내부 지침 탐색 질문을 정기 실행하고 숨은 규칙 설명 답변 차단률과 정상 답변 손실률로 확인함

## Ⅶ. 결론

- 프롬프트 유출은 숨은 지침이 곧 공격 설명서가 되는 문제이므로 프롬프트 최소화와 비밀 분리가 먼저임
