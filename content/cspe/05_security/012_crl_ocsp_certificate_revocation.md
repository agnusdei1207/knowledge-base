## 미리 알고가기

- 인증서 폐지: 유효기간 전이라도 인증서를 신뢰 대상에서 제외하는 조치임
- CRL: CA가 폐지된 인증서 일련번호 목록을 주기적으로 배포하는 방식임
- OCSP: 클라이언트가 특정 인증서 상태를 온라인으로 질의하는 방식임
- OCSP Stapling: 서버가 OCSP 응답을 미리 받아 TLS 핸드셰이크에 첨부하는 방식임
- Soft-fail: 폐지 상태 확인 실패 시 연결을 허용하는 처리 방식임

## Ⅰ. 개요

- **정의/개념**: CRL과 OCSP는 유효기간이 남은 인증서의 폐지 여부를 확인하는 PKI 상태 검증 절차임
- **배경/필요성**: 개인키 유출, 오발급, 소유권 변경이 발생하면 만료 전 인증서도 신뢰 경로에서 제외해야 함

## Ⅱ. 특징

- CRL은 목록 배포 방식이라 단순하지만 목록 크기와 갱신 주기가 부담임
- OCSP는 인증서별 상태 확인이 가능하지만 응답 서버 가용성에 의존함
- OCSP Stapling은 클라이언트 질의를 줄이고 개인정보 노출을 낮춤
- 폐지 확인 실패 처리 정책은 보안성과 가용성 사이의 운영 결정임

## Ⅲ. 종류 및 비교

| 구분 | CRL | OCSP | OCSP Stapling |
|:---|:---|:---|:---|
| 확인 방식 | 폐지 목록 다운로드 | 인증서별 상태 질의 | 서버가 상태 응답 첨부 |
| 장점 | 구조 단순, 오프라인 검증 가능 | 최근 폐지 상태 확인 | 지연과 개인정보 노출 감소 |
| 한계 | 목록 크기, 갱신 지연 | 응답 서버 의존 | 서버 설정과 갱신 필요 |
| 적용 판단 | 내부망·대량 검증 | 공개 인증서 상태 확인 | TLS 성능·프라이버시 개선 |

> 요약: 폐지 검증은 CRL과 OCSP 중 하나의 이름보다 갱신 지연과 실패 처리 정책이 판단 기준임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 인증서 일련번호 | 폐지 대상 식별 |
| 폐지 사유 | 키 유출, CA compromise 등 상태 설명 |
| CRL 배포 지점 | 목록을 받을 URL |
| OCSP Responder | 인증서 상태 질의 응답 서버 |
| Next Update | 상태 정보 갱신 시점 |

```text
클라이언트 -> 인증서 수신 -> CRL/OCSP 확인 -> good/revoked/unknown 판단 -> 연결 결정
```

## Ⅴ. 원리 및 절차 흐름도

1. **폐지 사유 발생**: 키 유출이나 오발급이 확인됨
2. **CA 폐지 등록**: 인증서 일련번호와 사유를 폐지 DB에 기록함
3. **상태 배포**: CRL 발행 또는 OCSP 응답을 갱신함
4. **클라이언트 확인**: 인증서 검증 중 폐지 상태를 조회함
5. **정책 적용**: revoked면 거부하고 unknown·timeout은 정책에 따라 처리함

## Ⅵ. 실무 적용 및 유의점

- 공개 웹에서는 OCSP 응답 장애 때문에 soft-fail 정책이 쓰일 수 있음
- 고보안 내부망은 폐지 확인 실패를 연결 실패로 처리함
- CRL 갱신 주기가 길면 폐지 반영 지연이 생김
- OCSP Stapling은 서버가 응답 갱신을 놓치면 클라이언트 오류가 발생함
- 짧은 수명 인증서는 폐지 의존도를 낮추지만 자동 갱신 체계가 필요함

## Ⅶ. 결론

- CRL과 OCSP는 인증서가 “아직 유효한가”를 시간·상태 기준으로 확인하는 절차임
- 답안에서는 목록 방식과 질의 방식의 차이, 갱신 지연, 실패 처리 정책을 함께 제시해야 함

## 작성 근거(검토용)

- 폐지 검증을 추상적 신뢰가 아니라 상태 조회 절차로 설명함
- `보장` 대신 good, revoked, unknown과 실패 처리 정책을 기준으로 둠
- CRL·OCSP·Stapling 비교가 운영 판단으로 이어지도록 구성함
