# 📖 【암기용】 개념 완전 이해

> 목적: 랜섬웨어 공격 분석과 대응을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 파일·시스템을 암호화하거나 데이터를 유출한 뒤 금전을 요구하는 공격
- **왜 필요한가**: 랜섬웨어는 서비스 중단과 정보 유출을 동시에 일으킨다. 복호화 키만 기다리면 업무 중단 시간이 늘고 법적 신고·고객 통지까지 지연된다.
- **핵심 직관**: 금고에 자물쇠를 채우는 것을 넘어 금고 속 문서를 복사해 협박하는 이중 갈취 구조임.

## 깊이 이해
- **배경·문제의식**: 초기 랜섬웨어는 개인 PC 파일 암호화 중심이었지만 현재는 AD 장악, 백업 삭제, 데이터 유출, 협력사 압박까지 포함하는 기업형 침해 사고가 됨.
- **작동 원리**: 피싱, VPN 취약점, RDP brute force로 침투한 뒤 권한 상승, lateral movement, 백업 삭제, 파일 암호화, 유출 사이트 공개 협박 순서로 진행한다.
- **비유**: 침입자가 사무실 열쇠를 훔친 뒤 문서함을 잠그고, 복사본을 외부에 가져가 공개하겠다고 협박하는 상황임.
- **구체 예시**: 공격자는 `vssadmin delete shadows`, 백업 에이전트 중지, 1분당 수천 개 파일 rename, C2로 50GB 압축 파일 업로드를 수행할 수 있다. 대응은 EDR 격리, 백업 3-2-1, RTO/RPO 확인이 핵심임.
- **흔한 오해·주의점**: 백업만 있으면 끝난다는 생각은 위험하다. 백업이 온라인으로 연결되어 있거나 복구 리허설이 없으면 암호화와 복구 실패가 동시에 발생한다.

## 연결 개념
- EDR - 대량 파일 변경, shadow copy 삭제, 암호화 프로세스 탐지
- 백업 3-2-1 - 3개 사본, 2종 매체, 1개 오프라인 또는 불변 저장
- Incident Response - 격리, 분석, 복구, 신고, 재발 방지 절차

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 랜섬웨어 답안은 침투부터 복구까지 타임라인, 침해 지표, 격리 위치, RTO/RPO, 재발 방지를 함께 써야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 랜섬웨어는 암호화, 백업 파괴, 데이터 유출, 금전 요구를 결합한 가용성·기밀성 침해임.
> 2. **가치**: 대응의 핵심은 감염 호스트 격리, 침해 범위 분석, 불변 백업 복구, 법적 신고, 재발 방지임.
> 3. **판단 포인트**: 3-2-1 백업, EDR, AD 계정 reset, RTO/RPO, 유출 여부 판단, 복구 리허설을 제시해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공격 절차 이해 확인 | 침투, 권한 상승, 백업 삭제, 암호화, 유출 협박 | 파일 암호화만 설명 |
| 대응 순서 판단 확인 | 격리, 증거 보존, 범위 산정, 복구, 신고 | 감염 PC 포맷부터 제시 |
| 복구 목표 확인 | 3-2-1, immutable backup, RTO/RPO | 백업 존재 여부만 언급 |

> 요약: 랜섬웨어 답안은 공격 타임라인과 복구 목표를 연결해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 암호화와 유출 기반 금전 요구 공격
- 배경: 랜섬웨어는 AD 장악, 백업 삭제, 데이터 유출, 파일 암호화를 결합해 가용성과 기밀성을 동시에 침해함.
- 필요성: 기업 대응은 EDR 격리, 3-2-1 불변 백업, RTO 4시간·RPO 15분, 유출 로그 분석 기준으로 복구해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
초기 침투 -> 권한 상승 -> AD/파일서버 탐색 -> 백업 삭제
-> 데이터 유출 -> 파일 암호화 -> 금전 요구
대응: EDR 격리 -> 포렌식 -> 3-2-1 백업 복구 -> 계정·취약점 조치
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 초기 침투 | 피싱, VPN 취약점, RDP brute force | MFA, 패치, 원격접속 제한 필요 |
| 내부 확산 | AD, SMB, PsExec, credential dump | 계정 reset, lateral movement 탐지 |
| 암호화·유출 | 파일 암호화, 압축 후 외부 전송 | 대량 rename, exfiltration 로그 |
| 복구 체계 | 3-2-1 백업, immutable storage | RTO/RPO, 복구 리허설 |

> 요약: 랜섬웨어는 침투·확산·파괴·협박 구조이며 대응은 격리와 백업 복구를 중심으로 설계함.

---

## Ⅲ. 동작원리 및 흐름도

```text
피싱/VPN/RDP 침투 -> 권한 상승 -> lateral movement -> 백업 무력화
-> 데이터 유출 -> 파일 암호화 -> 랜섬 노트 생성
-> EDR 격리 -> 범위 분석 -> 백업 복구 -> 재발 방지
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 초기 침투 경로 확인 | VPN log, mail log, RDP 실패 횟수 |
| 2 | 권한 상승·내부 이동 분석 | AD event 4624/4625/4672, PsExec |
| 3 | 백업 삭제·암호화 행위 탐지 | vssadmin, wbadmin, file rename burst |
| 4 | 유출 여부와 피해 범위 산정 | proxy, DNS, DLP, 대용량 업로드 |
| 5 | 격리·복구·재발 방지 수행 | RTO/RPO, 백업 무결성, 패치율 |

> 요약: 랜섬웨어 대응은 감염 파일 복구보다 침투 경로, 백업 파괴, 유출 여부를 먼저 확인해야 함.

## Ⅳ. 특징

| 구분 | 단순 악성코드 대응 | 랜섬웨어 대응 체계 | 수치·로그 포인트 |
|:---|:---|:---|:---|
| 피해 범위 | 단말 치료 | 업무 서비스·AD·백업 영향 산정 | 감염 호스트, 공유폴더, 계정 수 |
| 탐지 | 시그니처 검사 | EDR 행위 탐지, SIEM 상관 | 대량 rename, shadow copy 삭제 |
| 복구 | 파일 복원 | immutable backup, clean rebuild | RTO 4시간, RPO 15분 예시 |
| 신고 | 내부 처리 | 개인정보·침해사고 신고 판단 | 유출 로그, 영향 고객 수 |

> 요약: 랜섬웨어는 가용성 복구와 기밀성 사고 판단을 동시에 수행해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 백업 | 온라인 백업 | 3-2-1 + immutable backup | 백업 저장소 계정 분리, WORM 보존 |
| 탐지 | AV 시그니처 | EDR 행위 탐지 + SIEM | file change rate, process tree 분석 |
| 복구 | 감염 장비 치료 | clean image 재구축 + 데이터 복원 | 재감염 0건, RTO/RPO 달성 |

> 요약: 랜섬웨어는 백업의 존재보다 불변성, 계정 분리, 복구 리허설 여부가 선택 기준임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 백업 동시 암호화 | 백업 계정·네트워크 공유 | immutable backup, offline copy | 백업 삭제 권한 0건 |
| 재감염 | 침투 경로 미제거 | VPN 패치, MFA, 계정 reset | 동일 IoC 재탐지 0건 |
| 유출 은폐 | 암호화만 조사 | proxy, DNS, DLP, storage 로그 분석 | 외부 전송 용량 |
| 복구 지연 | 리허설 미수행 | 분기 1회 복구 훈련 | RTO/RPO 준수율 |

> 요약: 백업 보호, 침투 경로 제거, 유출 판단, 복구 훈련이 재발 방지의 핵심 통제임.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지·격리 | EDR 격리 15분 이내 | EDR isolation timestamp |
| 백업 | 3-2-1, 1개 immutable/offline, RPO 15분 | 백업 리포트, restore test |
| 복구·재발 | RTO 4시간, 패치율 95%, 재감염 0건 | DR 리허설, vulnerability scan |

> 요약: 운영 성공은 격리 시간, 백업 복구 가능성, RTO/RPO 달성, 재감염률로 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 예방: MFA, VPN·RDP 제한, 취약점 패치 SLA 14일, EDR, 이메일 sandbox, 관리자 계정 분리로 초기 침투 확률을 낮춤.
2. 대응: 감염 의심 호스트와 공유폴더를 15분 이내 격리하고 메모리 덤프, AD 로그, proxy 로그, 백업 삭제 로그를 보존함.
3. 복구: 3-2-1 백업 중 immutable 사본으로 clean image에 복원하고 RTO 4시간, RPO 15분, 재감염 0건을 확인함.

**결론 (2줄):**
- 기술사 판단: 복호화 키 확보보다 침투 경로 제거, 백업 무결성 검증, 유출 여부 판단이 우선임.
- 향후 방향: 랜섬웨어는 이중·삼중 갈취로 진화하므로 EDR, XDR, CTI, immutable backup, 법무·홍보 대응 체계를 통합해야 함.
