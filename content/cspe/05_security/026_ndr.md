## Ⅰ. 개요
- **정의**: 네트워크 트래픽을 지속적으로 분석하여 이상 행위를 탐지하고 자동 대응하는 보안 솔루션임
- **배경/필요성**: 시그니처 기반 IDS/IPS(023 참조)로는 미지 위협·내부 횡이동을 탐지하기 어려워 행위 기반 분석이 필요함
- **비유**: 건물 내 전체 복도의 동선을 AI 카메라로 분석하여 비정상 이동을 감지하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IDS/IPS 대비 NDR의 차별점 | 메타데이터·행위 분석·East-West 감시 | NDR은 시그니처가 아닌 기준선 기반 탐지임을 구분 |

> 요약: 네트워크 메타데이터·행위 분석으로 미지 위협과 내부 횡이동을 탐지·대응하는 솔루션임

## Ⅱ. 구성요소
```text
Network Tap/Span --> [ Traffic Sensor ] --> [ Analytics Engine ] --> Alert/Response
                                                   |
                                          +--------+--------+
                                          |                  |
                                     ML Model         Baseline DB
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Traffic Sensor | 네트워크 탭/미러링으로 패킷·메타데이터를 수집함 | 도로 위 CCTV |
| Analytics Engine | ML/통계 모델로 트래픽 행위를 분석·이상 탐지 수행함 | 교통 흐름 AI 분석 시스템 |
| Baseline DB | 정상 트래픽 패턴의 기준선을 저장·갱신하는 데이터베이스임 | 평소 교통량 기록부 |
| Response Module | 탐지된 위협에 대해 격리·차단·알림 등 자동 대응을 수행함 | 이상 차량 자동 차단 게이트 |

> 요약: 센서·분석 엔진·기준선 DB·대응 모듈이 네트워크 위협을 탐지·대응함

## Ⅲ. 절차
```text
트래픽 수집 --> 메타데이터 추출 --> 행위 분석 --> 탐지/대응
```
- 1단계: 네트워크 탭·스팬 포트에서 전체 트래픽을 패시브 방식으로 수집함
- 2단계: 패킷에서 5-tuple·DNS·TLS 핸드셰이크 등 메타데이터를 추출함
- 3단계: ML 모델이 Baseline DB 대비 편차를 분석하여 이상 행위를 탐지함
- 4단계: 위협 등급에 따라 경보 발생·세션 차단·SOAR(029 참조) 연동 대응을 수행함

> 요약: 패시브 수집 후 메타데이터 기반 행위 분석으로 위협을 탐지·대응함

## Ⅳ. 문제점
- 암호화 트래픽 분석 한계: TLS 페이로드 내용을 복호화 없이 분석해야 하므로 탐지 정확도가 저하됨
- 대용량 데이터 처리 부담: 전체 트래픽 메타데이터 저장·분석에 고성능 인프라가 요구됨
- 기준선 오염 위험: 공격이 점진적으로 진행되면 기준선에 반영되어 미탐이 발생함

> 요약: 암호화 한계·데이터 부담·기준선 오염이 NDR의 주요 과제임

## Ⅴ. 개선방안
1. 단기: TLS 핸드셰이크 메타데이터(JA3/JA4 핑거프린트)를 활용하여 암호화 트래픽 탐지력을 보완함
2. 중기: 스트림 처리 아키텍처를 적용하여 대용량 메타데이터를 실시간 분석함
3. 장기: XDR(027 참조) 통합으로 엔드포인트·클라우드 컨텍스트를 결합하여 기준선 정확도를 향상함

> 요약: 메타 핑거프린트, 스트림 처리, XDR 통합으로 탐지 정확도를 향상함

## Ⅵ. 전망
- 발전 방향: NDR이 XDR 플랫폼의 네트워크 텔레메트리 공급원으로 통합되는 추세임
- 기술사적 판단: East-West 트래픽 감시가 Zero Trust 구현의 핵심 가시성 수단으로 부상함
- 기술사 제언: NDR·EDR(030 참조)·SIEM(028 참조) 삼각 연동으로 SOC 가시성 확보가 필요함
