## 미리 알고가기

- SIEM은 로그를 한곳에 저장하는 기능과 실시간 상관분석 기능을 결합한 보안 분석 플랫폼임
- 단순 로그 서버와의 차이는 정규화, 상관분석, 경보, 포렌식 지원에 있음
- 성능보다 먼저 use case와 수집 범위와 저장 비용을 설계해야 운영 가치가 생김

## Ⅰ. 개요

- **정의/개념**: SIEM은 보안 로그와 이벤트를 통합 수집·정규화하고 상관분석, 경보, 포렌식 검색을 제공하는 플랫폼임
- **배경/필요성**: 공격 징후는 여러 장비에 분산됨. 전체 맥락을 보려면 단일 저장과 실시간 상관분석이 필요함

## Ⅱ. 특징

- 이기종 로그를 공통 스키마로 정규화해 검색과 상관분석을 가능하게 함
- 실시간 규칙과 과거 이력 분석으로 탐지와 감사 대응을 함께 지원함
- CTI, ATT&CK 매핑, SOAR 연계로 경보의 맥락을 보강함
- 수집량이 커질수록 저장 비용과 규칙 튜닝 비용이 급증함

## Ⅲ. 종류 및 비교

| 판단 기준 | 로그 관리 서버 | SIEM |
|:---|:---|:---|
| 핵심 역할 | 저장과 조회 중심 | 저장 + 상관분석 + 경보 |
| 데이터 처리 | 원문 위주 | 정규화와 맥락화 |
| 활용 목적 | 감사와 추적 | 탐지, 대응, 포렌식 |
| 대표 한계 | 실시간 탐지 약함 | 규칙과 비용 관리 부담 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Collector | 다양한 장비와 시스템에서 로그를 수집하는 입력 계층으로 에이전트와 Syslog와 API를 사용함 |
| Normalization Layer | 시간과 필드와 자산 정보를 공통 형식으로 맞춰 상관분석 가능 상태로 바꾸는 정제 계층임 |
| Correlation and Analytics | 규칙, 통계, CTI 매칭으로 사건 후보를 만드는 탐지 계층임 |
| Storage and Search | 장기 저장과 빠른 검색을 제공해 감사와 포렌식에 쓰이는 저장 계층임 |
| Dashboard and Alerting | 경보, 티켓, 대시보드로 분석가에게 결과를 전달하는 운영 계층임 |

```text
+-----------+    +----------------+    +----------------+    +----------------+
| Collector | -> | Normalize      | -> | Correlate      | -> | Alert/Search   |
+-----------+    +----------------+    +----------------+    +----------------+
                                                     |
                                                     v
                                               +----------------+
                                               | Storage        |
                                               +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 로그 수집      | -> | 정규화/보강   | -> | 상관분석      | -> | 경보 생성      | -> | 조사/포렌식    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **로그 수집**: 여러 장비와 서비스에서 이벤트를 수집함
2. **정규화와 보강**: 자산 정보와 사용자 정보와 위협 정보를 덧붙임
3. **상관분석**: 시간과 사용자와 자산 기준으로 이벤트를 연결함
4. **경보 생성**: 규칙 조건을 만족하면 사건 후보를 생성함
5. **조사와 포렌식**: 분석가가 원인과 범위를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 중앙 관제는 핵심 use case와 보관 기간을 먼저 정의하고 ingest 대비 경보 적중률·TB당 비용·검색 지연으로 확인함
2. 하이브리드 환경은 공통 스키마와 자산 식별자를 맞추고 파싱 성공률·상관분석 실패율로 확인함

## Ⅶ. 결론

- SIEM은 로그 저장소가 아니라 탐지와 포렌식을 위한 상관분석 플랫폼이므로 수집 범위와 정규화 품질이 효과를 결정함
