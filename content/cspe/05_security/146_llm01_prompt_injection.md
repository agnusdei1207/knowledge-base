## 미리 알고가기

- OWASP LLM Top 10은 생성형 AI 서비스의 대표 위험을 정리한 보안 기준표임
- 시스템 프롬프트는 모델의 역할과 금지 규칙을 담은 내부 지침임
- 외부 문서 입력은 검색 결과, 파일, 웹페이지처럼 모델이 함께 읽는 비신뢰 콘텐츠임

## Ⅰ. 개요

- **정의/개념**: LLM01 프롬프트 인젝션은 사용자 입력이나 외부 문서가 모델의 원래 지침과 출력 행동을 바꾸게 만드는 OWASP 2025 최우선 위험 항목임
- **배경/필요성**: LLM은 텍스트를 명령과 데이터로 엄격히 구분하지 못함. 평범한 문장이나 숨은 문자열도 모델이 읽는 순간 공격이 될 수 있음

## Ⅱ. 특징

- 직접 입력뿐 아니라 외부 문서를 통한 간접 공격까지 함께 다룸
- 유해 답변 생성, 권한 우회, 정보 유출, 도구 오남용으로 연결될 수 있음
- 단일 필터보다는 입력 분리, 출력 검토, 권한 축소를 함께 요구함
- 탈옥 공격도 안전 규칙 우회를 노리는 하위 형태로 볼 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 |
|:---|:---|:---|
| 공격 위치 | 사용자가 대화 입력에 지시를 직접 넣음 | 외부 문서나 웹페이지에 지시를 숨김 |
| 자주 생기는 환경 | 일반 챗봇, 테스트 우회 | 검색 증강 생성, 브라우저 에이전트, 메일 요약 |
| 사용자가 알아채기 | 비교적 쉬움 | 검색 과정에 섞여 잘 안 보일 수 있음 |
| 방어 초점 | 시스템 지침 보호와 출력 제어 | 외부 콘텐츠 격리와 도구 제한 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 입력 | 모델을 흔드는 공격 문장이 들어오는 시작점임 |
| 시스템 지침 | 모델이 지켜야 할 역할과 안전 규칙임 |
| 외부 문서 입력 | 검색과 파일 처리 과정에서 함께 들어오는 비신뢰 데이터임 |
| 모델 해석 계층 | 여러 지시의 우선순위를 잘못 판단하면 취약해짐 |
| 출력·도구 제어 | 위험 답변과 외부 실행을 마지막에 막는 계층임 |

```text
사용자 입력 + 외부 문서 + 시스템 지침 -> 모델 해석 -> 응답/도구 호출 -> 출력·권한 제어
```

## Ⅴ. 원리 및 절차 흐름도

```text
공격 입력 유입 -> 시스템 지침과 충돌 -> 모델이 공격 문장 수용 -> 잘못된 응답 또는 실행 -> 차단 또는 노출
```

1. **공격 입력 유입**: 사용자 문장이나 외부 문서에 공격 지시가 섞여 들어옴
2. **지시 충돌**: 시스템 규칙과 공격 지시가 동시에 모델에 전달됨
3. **공격 문장 수용**: 모델이 우선순위를 잘못 잡아 공격 지시를 따름
4. **위험 행동 발생**: 잘못된 답을 하거나 도구를 과하게 호출함
5. **차단 또는 노출**: 후단 검사가 약하면 그대로 서비스 밖으로 나감

## Ⅵ. 실무 적용 및 유의점

1. RAG와 도구 호출 서비스는 직접·간접 인젝션 시험 세트를 모두 돌리고 승인 없는 고위험 실행을 막아 우회 성공률과 도구 차단 수로 확인함
2. 다국어와 난독화 문자열을 허용하는 서비스는 입력 정규화와 출력 검토를 함께 두고 난독화 우회 재현 건수와 민감정보 유출 건수로 점검함

## Ⅶ. 결론

- LLM01은 텍스트를 곧 명령으로 읽는 모델 특성에서 나오므로 입력 분리와 권한 제어를 기본값으로 잡아야 함
