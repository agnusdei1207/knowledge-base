## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 데이터베이스의 통계 질의 결과에 수학적 노이즈를 주입하여, 특정 개인의 정보 포함 여부를 유추할 수 없도록 보장하는 기술임 |
| **배경/필요성** | 기존의 단순 비식별화(K-익명성 등) 기법이 외부 배경지식 결합 및 재식별 공격에 극도로 취약함이 증명됨에 따른 대안 필요 |
| **출제 의도** | 프라이버시 예산(Privacy Budget, Epsilon)의 개념과 노이즈 주입을 통한 통계적 유용성-보안 트레이드오프 이해 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Original DB      |      |  Noise Injection  |      |  Query Result     |
| (개인정보 포함 DB)+----->| (라플라스/가우스) +----->| (익명화된 통계치) |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **프라이버시 예산 (엡실론, ε)** | 허용되는 프라이버시 유출의 최대 허용치로, 작을수록 프라이버시 보호가 강하고 통계 정확도는 낮아짐 | 사진에 적용하는 모자이크 강도 |
| **노이즈 주입 (Noise)** | 질의 결과나 수집 데이터에 수학적 분포(라플라스 분포 등)를 따르는 임의의 오차 값을 섞는 과정임 | 통계 숫자에 무작위 주사위 값 더하기 |
| **민감도 (Sensitivity)** | DB에 개인 1명의 데이터가 추가/삭제될 때 결과값이 최대로 변할 수 있는 폭풍(영향력)의 크기임 | 한 사람이 빠질 때 평균치가 변하는 정도 |

> 요약: 개별 데이터의 존재 여부가 전체 통계 결과에 미치는 영향을 수학적으로 은폐하는 기법임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 질의 요청   |-->| 2. 민감도 분석 |-->| 3. 노이즈 생성 |-->| 4. 결과 반환   |
| (분석가가 조회)|   | (최대 변화량)  |   | (ε 기반 오차)  |   | (안전한 통계값)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **질의 요청**: 데이터 분석가가 원본 데이터베이스에 특정 통계 질의(예: 특정 질병 환자 수 평균)를 요청함
2. **민감도 분석**: 시스템 내부에서 해당 질의로 인해 데이터 결과가 변할 수 있는 최대 민감도(Sensitivity)를 계산함
3. **노이즈 생성 및 주입**: 사전에 설정된 프라이버시 예산(ε)과 계산된 민감도에 비례하여 라플라스 등 확률적 노이즈를 생성해 원본 결과에 더함
4. **결과 반환**: 개인정보 식별이 수학적으로 불가능하게 약간 왜곡(오차 포함)되었으나, 거시적 통계 트렌드는 유지되는 결과를 분석가에게 반환함

> 요약: 질의의 파급력을 계산하여 적절한 양의 무작위 노이즈를 섞어 통계적 정확성과 프라이버시를 맞교환함.

## Ⅳ. 문제점
* **통계적 유용성 저하**: 프라이버시를 강력하게 보호(작은 ε)할수록 노이즈가 과도하게 추가되어 분석 데이터로서의 가치(정확도)가 심각하게 훼손됨
* **프라이버시 예산 고갈 문제**: 동일한 DB에 반복적으로 질의를 수행하면 주입된 노이즈가 상쇄되어 결국 원본을 역추적할 수 있게 됨(예산 삭감 현상)
* **국소적 모델(LDP)의 노이즈 과잉**: 단말기(사용자)에서부터 노이즈를 섞어 보내는 로컬 DP의 경우, 서버 취합 시 노이즈가 누적되어 전체 분석 품질이 극도로 저하

## Ⅴ. 개선방안
* **단기 방안 (예산 관리 통제)**: 쿼리마다 소비되는 프라이버시 예산을 추적하는 매니저 시스템을 구축하여 총 예산 한도 도달 시 질의 강제 차단
* **중기 방안 (적응형 예산 할당)**: 질의의 중요도와 분석 목적에 따라 엡실론(ε) 값을 동적으로 조절하여 유용성과 보호 강도 간 최적의 균형점 도출
* **장기 방안 (합성 데이터 결합)**: GAN 등의 AI 모델과 차등 프라이버시를 결합하여, 원본과 통계적 특성은 동일하되 실존 인물은 없는 'DP-합성 데이터(Synthetic Data)' 생성 배포

## Ⅵ. 전망
* 단순 비식별화 방식의 근본적 한계를 대체하는 수학적 입증 기반 익명화 기술로, 애플(Siri 연합학습), 구글 등 빅테크의 핵심 데이터 수집 표준으로 채택됨
* 인공지능 모델 학습 시 훈련 데이터(개인정보)의 역추출을 막기 위해 딥러닝 최적화에 노이즈를 섞는 DP-SGD 등 AI 보안 영역으로 전면 확장 중임
