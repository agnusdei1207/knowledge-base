## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 공개키와 개인키 한 쌍을 사용하여 암호화와 복호화를 수행하는 기법임 |
| **배경/필요성** | 대칭 암호의 키 분배 문제 해결 및 디지털 환경에서 부인 방지를 위한 수단 필요 |
| **출제 의도** | 소인수분해(RSA), 이산대수(ECC) 등 수학적 난제에 기반한 암호학적 원리 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Public Key (공개)|      |   Encryption      |      | Private Key (개인)|
|  (누구나 접근)    +----->|  (기밀성 보장)    +----->|  (소유자만 복호)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **공개키 (Public Key)** | 외부에 공개되며 데이터 암호화 또는 서명 검증에 사용됨 | 열려 있는 자물쇠 |
| **개인키 (Private Key)** | 소유자만 안전하게 보관하며 복호화 또는 서명 생성에 사용됨 | 자물쇠를 여는 유일한 열쇠 |
| **수학적 난제 알고리즘** | 소인수분해(RSA) 등 역산이 극히 어려운 수학적 알고리즘임 | 뚫기 불가능한 특수 금고 |

> 요약: 수학적으로 연관된 키 쌍(공개키, 개인키)을 활용하여 기밀성과 인증을 분리 구현한 체계임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 키 쌍 생성  |-->| 2. 공개키 배포 |-->| 3. 데이터 암호 |-->| 4. 데이터 복호 |
| (개인/공개키)  |   | (디렉터리 등록)|   | (수신자 공개키)|   | (수신자 개인키)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **키 쌍 생성**: 수신자가 자신의 개인키와 공개키 한 쌍을 수학적 알고리즘을 통해 생성함
2. **공개키 배포**: 생성된 공개키를 누구나 접근할 수 있도록 공개 디렉터리 등에 배포함
3. **데이터 암호화**: 송신자가 수신자의 공개키를 이용해 평문을 암호화함
4. **데이터 복호화**: 수신자가 자신만이 보유한 개인키로 암호문을 평문으로 복호화함

> 요약: 수신자의 공개키로 암호화하고 수신자의 개인키로 복호화하여 키 분배 없이 안전성을 확보함.

## Ⅳ. 문제점
* **느린 처리 속도**: 대칭 암호 대비 복잡한 수학 연산으로 인해 처리 속도가 매우 느림
* **키 길이 증가 부담**: 컴퓨팅 파워 증가로 안전성 확보를 위해 더 긴 키 길이(예: RSA-2048)가 필요함
* **중간자 공격(MITM) 위협**: 통신 중간에서 공개키를 가로채어 자신의 공개키로 변조할 위험이 있음

## Ⅴ. 개선방안
* **단기 방안 (하이브리드 암호)**: 대칭키 교환 용도로만 비대칭 암호를 사용하고 실제 통신은 대칭키로 수행
* **중기 방안 (ECC 도입)**: 짧은 키 길이로도 동일한 보안 강도를 제공하는 타원 곡선 암호(ECC)로 전환
* **장기 방안 (PKI 구축)**: 공인 인증 기관(CA)을 통한 공개키 인증서(PKI) 발급으로 중간자 공격 원천 차단

## Ⅵ. 전망
* 양자 컴퓨터의 쇼어(Shor) 알고리즘으로 기존 비대칭 암호가 무력화될 위험이 있어 PQC로의 전환이 시급함
* 인증 기반 통신의 핵심 요소로서 보안 강도와 경량화 간 균형을 맞추는 연구가 지속될 전망임
