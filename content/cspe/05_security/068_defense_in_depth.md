## 미리 알고가기

- 심층 방어는 하나의 장비나 정책이 뚫릴 수 있다는 전제로 여러 계층에 통제를 배치하는 전략임
- 예방만으로는 충분하지 않으므로 탐지와 대응과 복구까지 계층에 포함해야 함
- 통제가 많아도 서로 연결되지 않으면 중복 투자나 탐지 공백이 생길 수 있음

## Ⅰ. 개요

- **정의/개념**: 심층 방어는 네트워크, 계정, 단말, 애플리케이션, 데이터, 운영 절차 등 여러 계층에 예방·탐지·대응·복구 통제를 겹쳐 배치해 공격 성공 확률과 피해 범위를 줄이는 보안 전략임
- **배경/필요성**: 공격자는 가장 약한 지점 하나만 뚫으면 되므로 단일 방어 수단에 의존하면 우회나 오탐 한 번으로 전체 피해가 커져 다층 통제 설계가 필요함

## Ⅱ. 특징

- 특정 통제의 실패를 전제로 다음 계층이 피해를 줄이도록 설계함
- 기술 통제와 함께 권한 정책과 백업과 대응 절차까지 포함함
- 동일한 통제를 반복 배치하는 것이 아니라 공격 흐름별 보완 관계를 만들어야 함
- 계층 간 로그 연계와 책임 분담이 없으면 실제 사고 시 작동하지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 방어 중심 | 심층 방어 |
|:---|:---|:---|
| 설계 관점 | 특정 장비나 정책에 의존 | 여러 계층의 보완 통제 조합 |
| 실패 영향 | 한 지점 우회 시 피해 확대 | 다음 계층에서 차단·탐지 가능 |
| 운영 요구 | 개별 장비 설정 중심 | 아키텍처, 로그, 대응 절차 연계 필요 |
| 적합성 | 단순 환경에 제한적 | 중요 자산과 복합 환경에 적합 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 예방 계층 | 네트워크 분리, MFA, 보안 구성, 취약점 조치로 초기 침투를 줄임 |
| 탐지 계층 | EDR, SIEM, 로그 분석으로 이상 행위를 찾음 |
| 대응 계층 | 격리, 차단, 권한 회수, 플레이북 실행으로 확산을 막음 |
| 복구 계층 | 백업, 재배포, 자격 증명 교체, 복구 계획으로 정상 상태를 회복함 |

```text
예방 -> 탐지 -> 대응 -> 복구
  |       |       |       |
계층별 통제가 서로 보완해 피해 범위를 줄임
```

## Ⅴ. 원리 및 절차 흐름도

```text
신뢰 경계 식별 -> 계층별 통제 배치 -> 로그 연계 -> 침해 시 차단/격리 -> 복구와 재설계
```

1. **신뢰 경계 식별**: 중요한 자산과 경계 지점을 나눔
2. **통제 배치**: 계층별로 예방과 탐지와 대응 수단을 배치함
3. **로그 연계**: 각 계층의 경보와 증적을 연결함
4. **침해 대응**: 한 계층이 실패해도 다른 계층이 확산을 막게 함
5. **복구와 재설계**: 사고 이후 취약한 계층을 보완함

## Ⅵ. 실무 적용 및 유의점

1. 인터넷 노출 서비스는 WAF만으로 방어를 끝내지 말고 MFA, 최소 권한, EDR, 백업과 함께 설계해야 하며 미탐 상황에서도 횡적 이동 차단 여부와 복구 시간 단축으로 확인함
2. 클라우드 환경은 네트워크 경계가 약해질 수 있으므로 계정·워크로드·데이터 계층 통제를 함께 설계해야 하며 계층별 로그 수집 완전성과 동일 시나리오 재훈련 시 탐지·차단 성공률로 확인함

## Ⅶ. 결론

- 심층 방어는 장비 수를 늘리는 전략이 아니라 한 계층의 실패를 다른 계층이 흡수하도록 설계해 피해를 줄이는 운영 원칙임
