# 📖 【암기용】 개념 완전 이해

> 목적: 심층 방어 전략을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 단일 보안 장비에 의존하지 않고 예방, 탐지, 대응, 복구 통제를 여러 계층에 배치하는 전략
- **왜 필요한가**: 방화벽, MFA, EDR 중 하나가 우회되어도 다음 계층에서 공격을 제한하거나 발견해야 한다.
- **핵심 직관**: 성벽 하나가 아니라 외곽 울타리, 출입통제, 내부 경보, 비상대응, 복구 계획을 겹쳐 두는 방식이다.

## 깊이 이해
- **배경·문제의식**: 공격자는 피싱, 취약점, 계정 탈취, 공급망, 내부자 경로 중 가장 약한 지점을 선택한다. 특정 통제가 실패할 수 있다는 전제를 두고 보완 통제를 다층으로 설계해야 한다.
- **작동 원리**: 자산과 신뢰 경계를 나누고 네트워크, ID, 엔드포인트, 애플리케이션, 데이터, 운영 계층에 통제를 배치한다. 각 계층은 예방, 탐지, 대응, 복구 역할 중 하나 이상을 담당한다.
- **비유**: 공항 보안처럼 입구 신분 확인, 수하물 검색, 탑승구 확인, CCTV, 비상 대응팀, 비행기 격리 절차가 단계별로 작동한다.
- **구체 예시**: 피싱으로 계정이 탈취되어도 MFA, 조건부 접근, 최소 권한, EDR 행위 탐지, DLP, 백업 복구가 순차적으로 피해 범위를 제한한다.
- **흔한 오해·주의점**: 장비를 많이 사는 것이 심층 방어가 아니다. 계층 간 탐지 신호, 대응 playbook, 복구 지표가 연결되어야 중복 투자와 탐지 공백을 줄일 수 있다.

## 연결 개념
- Zero Trust - 신뢰 경계 내부도 지속 검증
- MITRE ATT&CK - 공격 단계별 방어 통제 매핑
- BCP/DR - 침해 이후 업무 복구 계층

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 심층 방어 답안은 보안 장비 나열이 아니라 신뢰 경계별 예방-탐지-대응-복구 통제와 로그 지표를 연결해야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 심층 방어는 하나의 통제 실패를 전제로 다층 통제를 배치해 공격 성공 확률과 피해 범위를 줄이는 전략임.
> 2. **가치**: 네트워크, ID, 단말, 애플리케이션, 데이터, 복구 계층에서 공격 흐름을 여러 지점에서 차단·탐지함.
> 3. **판단 포인트**: 각 계층의 방어 위치, 로그 수집, 대응 책임, 복구 목표(RTO/RPO)를 명확히 해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 아키텍처 설계 확인 | 예방, 탐지, 대응, 복구 계층과 신뢰 경계 | 방화벽·백신 등 제품명만 나열 |
| 공격 흐름 차단 판단 확인 | initial access, lateral movement, exfiltration별 방어 위치 | 공격 단계와 통제 매핑 누락 |
| 운영 지표 이해 확인 | MTTD, MTTR, RTO/RPO, coverage, 로그 연계 | 탐지와 복구 지표 없이 설명 |

> 요약: 이 문제는 통제 목록보다 공격 흐름별 어느 계층에서 막고, 탐지하고, 복구할지의 설계 판단을 요구함.

## Ⅰ. 개요 및 필요성

- 개요: 다층 보안 통제 전략
- 배경: 단일 통제는 우회, 설정 오류, 운영 누락으로 실패할 수 있어 침입 차단만으로는 계정 탈취와 내부 이동을 끊기 어려움.
- 필요성: NIST CSF의 Identify·Protect·Detect·Respond·Recover 단계에 맞춰 예방, 탐지, 대응, 복구 통제를 신뢰 경계별로 배치해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
외부 위협 -> 경계/네트워크 -> ID/접근 -> 엔드포인트
          -> 애플리케이션/API -> 데이터 -> 백업/복구
          -> SOC 탐지/대응으로 피드백
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 경계/네트워크 | WAF, NGFW, IDS/IPS, segmentation | 인터넷 노출면과 동서 트래픽 통제 |
| ID/접근 | MFA, 조건부 접근, 최소 권한, PAM | 계정 탈취 후 권한 확산 제한 |
| 엔드포인트 | EDR, hardening, application control | 악성 행위와 lateral movement 탐지 |
| 애플리케이션/API | SAST/DAST, API gateway, input validation | 신뢰 경계와 입력 검증 |
| 데이터/복구 | 암호화, DLP, immutable backup, DR | 유출 방지와 RTO/RPO 달성 |

> 요약: 심층 방어는 경계부터 복구까지 계층별 통제를 배치하고 SOC가 로그를 결합해 대응하는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
위협 모델링 -> 자산/신뢰 경계 식별 -> 계층별 통제 배치
-> 로그 수집/상관분석 -> incident response -> containment
-> 복구/재발 방지 -> 통제 재검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | crown jewel과 공격 경로 식별 | ATT&CK scenario coverage 80% |
| 2 | 계층별 예방 통제 배치 | MFA, WAF, EDR 적용률 95% |
| 3 | 로그 수집과 탐지 룰 매핑 | critical log source 누락 0건 |
| 4 | 대응 playbook으로 격리·차단 | MTTD 30분, MTTR 4시간 |
| 5 | 백업 복구와 원인 재검증 | RTO 4시간, RPO 15분 |

> 요약: 동작 흐름은 공격 경로를 모델링한 뒤 계층별 통제와 로그를 연결하고 대응·복구 결과로 다시 검증하는 구조임.

## Ⅳ. 특징

| 구분 | 단일 통제 | 심층 방어 | 수치/판단 포인트 |
|:---|:---|:---|:---|
| 방어 위치 | 특정 경계 1곳 | 네트워크, ID, 단말, 앱, 데이터 | 계층별 coverage 80% 이상 |
| 실패 전제 | 통제 성공 가정 | 우회와 실패를 전제 | 보완 통제 2개 이상 |
| 탐지 방식 | 단일 로그 | SIEM/XDR 상관분석 | critical log source 100% |
| 복구 관점 | 차단 중심 | 대응과 복구 포함 | RTO 4시간, RPO 15분 |

> 요약: 심층 방어는 차단 실패를 전제로 탐지, 대응, 복구까지 포함해 피해 범위를 제한하는 전략임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 경계 보안 중심 | 경계, ID, 단말, 앱, 데이터, 복구 | 원격근무·클라우드·SaaS 환경 |
| 비용/운영 | 장비 단위 도입 | 통제 매핑과 로그 통합 필요 | SOC 또는 MSS 운영 시 |
| 위험 통제 | 침입 차단 목표 | 침해 가정과 피해 제한 | APT, 랜섬웨어, 내부자 위협 |

> 요약: 클라우드와 원격접속 환경에서는 경계 보안만으로 부족하므로 ID와 데이터 계층 중심의 심층 방어가 필요함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 중복 투자 | 장비별 독립 도입 | ATT&CK 기반 통제 매핑 | 중복 통제 제거 건수 |
| 탐지 공백 | 로그 미수집·룰 부재 | SIEM use case, XDR telemetry | log source 누락 0건 |
| 대응 지연 | playbook 부재 | SOAR, tabletop exercise | MTTR 4시간 |
| 복구 실패 | 백업 변조·미검증 | immutable backup, restore drill | 복구 훈련 반기 1회 |

> 요약: 심층 방어의 리스크는 중복보다 공백이며, 통제 매핑과 로그·복구 훈련으로 검증해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 계층 커버리지 | 주요 공격 단계 80% 이상 | ATT&CK Navigator, control matrix |
| 탐지 시간 | MTTD 30분 이하 | SIEM case timeline |
| 대응 시간 | MTTR 4시간 이하 | IR ticket, SOAR workflow |
| 복구 능력 | RTO 4시간, RPO 15분 | DR drill, backup restore test |

> 요약: 성과는 계층 수가 아니라 공격 단계 커버리지, 탐지·대응 시간, 복구 목표 달성으로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 통제 매핑: crown jewel 기준으로 ATT&CK TTP를 선정하고 network, identity, endpoint, application, data, recovery 계층별 통제를 배치함.
2. 탐지·대응 연결: WAF, IdP, EDR, DB audit, cloud audit 로그를 SIEM/XDR에 수집하고 MTTD 30분, MTTR 4시간을 기준으로 playbook을 운영함.
3. 복구 재검증: immutable backup, DR site, 복구 훈련을 반기 1회 수행하고 랜섬웨어 시나리오에서 RTO/RPO 달성 여부를 기록함.

**결론 (2줄):**
- 기술사 판단: 단일 경계가 명확한 소규모 시스템은 기본 통제 중심, 클라우드·원격·공급망 환경은 ID와 데이터 중심 심층 방어를 선택해야 함.
- 향후 방향: Zero Trust와 XDR 기반으로 신뢰 경계 내부의 행위를 계속 검증하고 복구 지표까지 보안 아키텍처에 포함해야 함.
