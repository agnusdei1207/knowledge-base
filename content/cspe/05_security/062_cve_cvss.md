## 미리 알고가기

- CVE는 취약점에 붙는 공통 식별자이고, CVSS는 그 취약점의 공격 난이도와 영향도를 점수로 표현하는 체계임
- 같은 CVE라도 조직의 자산 중요도와 외부 노출 여부에 따라 실제 조치 우선순위는 달라질 수 있음
- CVSS 점수는 출발점이지 최종 위험 판단 전체를 대신하지 않음

## Ⅰ. 개요

- **정의/개념**: CVE는 전 세계에서 같은 취약점을 같은 이름으로 추적하게 하는 표준 식별자이며, CVSS는 공격 벡터와 권한 요구와 기밀성·무결성·가용성 영향을 반영해 심각도를 수치화하는 채점 체계임
- **배경/필요성**: 벤더와 스캐너와 운영팀이 서로 다른 이름과 기준을 쓰면 취약점 추적과 패치 우선순위가 혼선에 빠지므로 공통 식별과 공통 점수 체계가 필요함

## Ⅱ. 특징

- CVE는 동일 취약점에 대한 참조 기준을 제공해 벤더 공지와 스캐너 결과와 티켓을 연결함
- CVSS는 취약점 자체의 기술적 심각도를 구조화해 비교를 쉽게 함
- 실제 운영에서는 CVSS 외에 KEV, EPSS, 자산 중요도, 인터넷 노출 여부를 함께 봐야 함
- 점수만으로 패치 순위를 고정하면 중요 서비스의 중간 점수 취약점을 놓칠 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | CVE | CVSS |
|:---|:---|:---|
| 역할 | 취약점 식별자 부여 | 취약점 심각도 산정 |
| 출력 형태 | `CVE-YYYY-NNNN` | 점수와 벡터 문자열 |
| 활용 목적 | 추적, 매핑, 참조 통일 | 우선순위, SLA, 보고 기준 |
| 한계 | 위험도는 직접 알려주지 않음 | 환경별 실제 위험을 모두 반영하지 못함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CVE ID | 취약점 식별과 공통 참조를 담당함 |
| CVSS Base Metrics | 공격 경로, 복잡도, 권한 요구, 영향도를 기준으로 기본 점수를 만듦 |
| Environmental Context | 자산 중요도와 보상 통제를 반영해 조직 내부 우선순위를 조정함 |
| 운영 연계 | 스캐너, ITSM, 패치 SLA, 대시보드에 점수와 식별자를 연결함 |

```text
CVE 식별 -> CVSS 기본 점수 산정 -> 조직 환경 보정 -> 패치 우선순위/예외 관리
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약점 공개 -> CVE 확인 -> CVSS 점수 해석 -> 자산 영향 반영 -> SLA 결정 -> 조치/재검증
```

1. **취약점 공개 확인**: 벤더 공지나 NVD에서 CVE를 식별함
2. **점수 해석**: CVSS 점수와 벡터로 공격 난이도와 영향 범위를 이해함
3. **환경 보정**: 인터넷 노출 여부와 자산 중요도와 보상 통제를 반영함
4. **SLA 결정**: 패치 기한과 예외 승인 기준을 정함
5. **조치와 재검증**: 패치나 우회 통제 적용 후 동일 CVE 노출 해소를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 취약점 관리 체계에서는 CVE를 기준 키로 통합하고 CVSS 점수만이 아니라 외부 노출과 실제 악용 정보까지 더해 우선순위를 정해야 하며 동일 CVE 고위험 자산의 SLA 준수율과 재점검 해소율로 확인함
2. 운영 시스템에서 CVSS 9점대라도 내부 격리 자산이면 예외 검토가 가능하지만 중간 점수라도 공개 서비스 인증 우회라면 긴급 대응해야 하므로 중요 자산 누락 여부와 예외 승인 근거 적정성으로 확인함

## Ⅶ. 결론

- CVE는 취약점을 공통 이름으로 묶고 CVSS는 우선순위 판단의 출발점을 제공하므로 실제 운영에서는 자산 맥락과 악용 가능성을 더해 조치 기준으로 변환해야 함
