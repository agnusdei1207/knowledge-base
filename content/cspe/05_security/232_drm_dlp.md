# 📖 【암기용】 개념 완전 이해

> 목적: DRM과 DLP를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: DRM은 파일 자체에 권한을 붙이고, DLP는 민감정보가 밖으로 나가는 경로를 탐지·차단한다.
- **왜 필요한가**: 개인정보·영업비밀·소스코드는 저장소를 떠난 뒤에도 유출될 수 있다. 파일 권한 통제와 반출 채널 통제를 함께 설계해야 한다.
- **핵심 직관**: DRM은 문서에 자물쇠를 달고, DLP는 회사 출입구·메일·웹업로드에서 내용물을 검사하는 보안 검색대이다.

## 깊이 이해
- **배경·문제의식**: 재택근무, SaaS, 협력사 공유가 늘면서 내부 파일이 메일·메신저·클라우드 저장소로 이동한다. 서버 접근통제만으로는 다운로드 이후 복사·전송·화면 캡처를 막기 어렵다.
- **작동 원리**: DRM은 문서 암호화, 열람·편집·인쇄 권한, 워터마크, 만료일을 파일에 적용한다. DLP는 엔드포인트·메일·웹·CASB 경로에서 주민번호, 카드번호, 기밀 키워드, 소스코드 패턴을 탐지하고 반출을 차단한다.
- **비유**: DRM은 기밀 문서를 열쇠가 있는 사람만 읽게 하는 봉투이고, DLP는 봉투 밖으로 나가는 모든 택배를 X-ray로 검사하는 절차이다.
- **구체 예시**: 계약서 PDF는 AES-256 암호화와 화면 워터마크를 적용하고, DLP는 이메일 첨부에서 주민번호 100건 이상 탐지 시 격리 및 보안 승인 절차를 실행한다.
- **흔한 오해·주의점**: DRM과 DLP는 대체 관계가 아니다. DRM은 파일 단위 사후 사용 통제에 강하고, DLP는 채널 단위 반출 차단과 사고 탐지에 강하다.

## 연결 개념
- CASB - SaaS 업로드·공유 링크·외부 계정 반출을 DLP 정책으로 통제한다.
- 데이터 분류 - 공개·대외비·기밀 등급이 있어야 DRM/DLP 정책이 작동한다.
- 개인정보 보호 - 주민번호·계좌번호·건강정보 탐지 규칙과 보관 로그가 감사 근거가 된다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: DRM·DLP는 제품 비교가 아니라 데이터 생명주기별 통제 지점과 CASB·엔드포인트 연계를 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DRM은 문서 암호화·권한·워터마크로 파일 자체를 통제하고, DLP는 내용 탐지·반출 차단·채널 통제로 유출 경로를 막는 데이터 보안 체계이다.
> 2. **가치**: 파일 저장 이후 사용권한과 메일·웹·USB·SaaS 반출 경로를 동시에 통제해 개인정보·영업비밀 유출 가능성을 낮춘다.
> 3. **판단 포인트**: 데이터 분류 정확도, 탐지 규칙 오탐률, 사용자 예외 승인, CASB·EDR·SIEM 연동이 운영 품질을 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DRM과 DLP 차이 이해 확인 | 암호화·권한·워터마크 vs 내용 탐지·반출 차단·채널 통제 | 둘을 모두 문서보안으로만 설명 |
| 데이터 유출 방지 설계 확인 | Endpoint, Network, Email, CASB DLP 배치 | 저장소 접근통제만 쓰고 반출 경로 누락 |
| 운영 리스크 판단 확인 | 오탐·업무 지연·예외 승인·로그 감사 | 전면 차단만 답하고 업무 연속성 누락 |

> 요약: 이 문제는 DRM·DLP 용어 설명보다 데이터 이동 단계별 통제와 오탐 관리 방안을 요구한다.

---

## Ⅰ. 개요 및 필요성

DRM·DLP는 데이터 유출을 줄이는 보안 통제이다. DRM은 파일 사용권한을 통제하고, DLP는 민감정보 반출 경로를 탐지·차단한다. 개인정보·소스코드·계약서가 SaaS와 외부 협업 도구로 이동하므로 저장소 보안과 반출 통제를 함께 설계해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Data Classification -> DRM Policy -> Encrypted Document -> Usage Control
                   +-> DLP Policy -> Endpoint/Email/Web/CASB -> Block/Quarantine
Audit Log -> SIEM -> Incident Response
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 분류 | 개인정보·영업비밀·공개 데이터 등급화 | 자동 라벨링, 사용자 라벨 확인 |
| DRM Agent | 문서 암호화, 열람·편집·인쇄·캡처 권한 제어 | AES-256, 워터마크, 만료일 |
| DLP Engine | 패턴·정규식·지문·ML 기반 내용 탐지 | 주민번호, 카드번호, 소스코드 |
| 채널 통제 | 메일·웹업로드·USB·프린터·SaaS 통제 | Endpoint, Network, CASB DLP |
| 감사·대응 | 차단 로그, 예외 승인, 사고 티켓 생성 | SIEM, SOAR 연계 |

> 요약: DRM은 파일에 권한을 붙이고 DLP는 데이터 이동 채널에서 내용을 검사해 차단·격리·감사를 수행한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
문서 생성 -> 등급 분류 -> DRM 권한 적용 -> 사용자 행위 통제
민감정보 전송 시도 -> DLP 내용 탐지 -> 정책 판단 -> 차단/승인/격리 -> 로그 감사
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 라벨과 소유자 식별 | 기밀 등급, 보관 기간, 소유 부서 |
| 2 | DRM 암호화와 권한 부여 | 열람·편집·인쇄 권한, 만료일 |
| 3 | DLP가 전송 채널 내용 검사 | 정규식, 파일 지문, 키워드, OCR |
| 4 | 정책에 따라 차단·격리·승인 요청 | 주민번호 100건 이상 차단 |
| 5 | 로그를 SIEM/SOAR로 전송 | 사용자, 파일, 채널, 정책 ID 기록 |

> 요약: DRM은 파일 사용 단계, DLP는 반출 시도 단계에서 정책을 적용하고 로그로 감사 가능성을 확보한다.

---

## Ⅳ. 특징

| 구분 | DRM | DLP | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 통제 대상 | 문서 파일 자체 | 데이터 내용과 이동 채널 | 파일 권한 vs 메일·웹·USB |
| 주요 기능 | 암호화, 권한, 워터마크 | 패턴 탐지, 반출 차단, 격리 | 주민번호 13자리, 카드 BIN |
| 적용 단계 | 생성·저장·열람 | 전송·복사·업로드 | Endpoint+CASB 연계 |
| 한계 | 화면 촬영·복호화 후 복사 위험 | 오탐·업무 지연 | 예외 승인 SLA 4시간 |

> 요약: DRM은 사후 사용 통제, DLP는 반출 채널 통제에 강하므로 데이터 등급과 업무 경로에 따라 병행 적용한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 저장소 ACL 중심 | DRM+DLP+CASB 연계 | 다운로드 이후 통제와 SaaS 반출 통제 필요 시 |
| 비용/성능 | 수동 검토 | 정책 기반 자동 탐지 | 오탐률 5% 이하, 차단 지연 2초 이하 |
| 운영/위험 | 업무 담당자 판단 의존 | 라벨·정책·예외 승인 프로세스 | 개인정보·영업비밀 규제 감사 필요 시 |

> 요약: DRM·DLP는 저장소 밖으로 이동한 데이터까지 통제해야 할 때 도입하며, 오탐률과 예외 처리 시간이 핵심 판단 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 과다 | 주민번호 유사 문자열, 테스트 데이터 | 샘플링 튜닝, 부서별 정책 분리 | 오탐률 5% 이하 |
| 업무 지연 | 전면 차단 정책, 승인 대기 | 위험도별 모니터링/차단 구분, SLA 4시간 | 승인 처리 시간 |
| 우회 반출 | 개인 SaaS, 화면 촬영, 압축 암호 | CASB, 워터마크, EDR 행위 탐지 | 미승인 SaaS 업로드 건수 |

> 요약: DRM·DLP 리스크는 오탐과 우회이며, 정책 튜닝·예외 승인·CASB 연계로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지 품질 | 민감정보 탐지 재현율 95% 이상 | 샘플 데이터셋 검증 |
| 반출 통제 | 고위험 채널 차단률 100% | DLP 정책 로그 |
| 감사 대응 | 로그 보관 1년 이상, 정책 변경 이력 | SIEM 리포트, 접근 감사 |

> 요약: 도입 효과는 탐지 재현율, 고위험 반출 차단률, 감사 로그 완전성으로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 데이터 라벨을 공개·대외비·기밀·개인정보 4등급으로 표준화하고, 기밀 문서에는 AES-256 DRM과 사용자 워터마크를 적용함
2. Endpoint·Email·Web Proxy·CASB DLP 정책을 통합하고, 주민번호 100건 이상·소스코드 저장소 압축 파일 외부 전송은 차단함
3. 예외 승인은 부서장+보안 승인 2단계로 처리하고, 승인 SLA 4시간·로그 보관 1년·월간 오탐률 5% 이하를 지표로 관리함

**결론 (2줄):**
- 기술사 판단: 파일 자체 통제가 필요한 설계도·계약서는 DRM 우선, 메일·SaaS 반출 위험은 DLP/CASB 우선 적용이 타당함
- 향후 방향: 데이터 분류 자동화와 UEBA 기반 행위 분석을 결합해 민감정보 이동 경로 중심 통제로 발전함
