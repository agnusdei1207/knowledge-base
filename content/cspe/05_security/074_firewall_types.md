## Ⅰ. 개요
- **정의**: 네트워크 트래픽을 사전 정의된 보안 규칙에 따라 허용/차단하는 보안 장비의 유형 분류
- **배경/필요성**: 위협이 L3/L4에서 L7 애플리케이션 계층으로 이동하면서 방화벽도 패킷 필터링에서 애플리케이션 인식까지 진화가 필요함
- **비유**: 단순 출입문(패킷 필터) → 신분증 확인(상태 추적) → 소지품 검사(NGFW)로 검문 수준이 높아지는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 방화벽 세대별 진화 | 패킷필터-상태추적-NGFW 차이 | 각 세대 검사 계층(L3/L4/L7) 명시 |

> 요약: 방화벽은 패킷 필터링에서 상태 추적, NGFW까지 검사 심도가 확장되어 옴

## Ⅱ. 구성요소
```text
패킷 필터(L3/L4) --> 상태 추적(Stateful) --> 프록시(L7) --> NGFW(L3-L7 통합)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 패킷 필터 | IP/포트 기반 ACL로 개별 패킷을 판단함 | 주소만 보는 경비 |
| 상태 추적 | TCP 세션 상태 테이블로 연결 문맥을 유지하며 검사함 | 방문 기록부 확인 |
| 애플리케이션 프록시 | L7 프로토콜을 해석하여 콘텐츠 수준 검사를 수행함 | 짐 내용물 검사관 |
| NGFW | IPS, 앱 식별, SSL 검사, 위협 인텔리전스를 통합함 | 종합 보안 검문소 |

> 요약: L3 패킷 필터부터 L7 NGFW까지 검사 범위와 문맥 인식이 단계적으로 확장됨

## Ⅲ. 절차
```text
패킷 수신 --> 헤더/상태 검사 --> 앱 프로토콜 식별 --> 정책 매칭/처리
```
- 1단계: 패킷 수신 — 인터페이스에 도착한 패킷의 L3/L4 헤더 정보를 추출함
- 2단계: 상태 검사 — 세션 테이블과 대조하여 기존 연결 여부와 상태 적합성을 판단함
- 3단계: 앱 식별 — DPI(Deep Packet Inspection)로 L7 프로토콜과 애플리케이션을 식별함
- 4단계: 정책 매칭 — 식별 결과와 보안 정책을 대조하여 허용, 차단, 로깅을 수행함

> 요약: 헤더 추출-상태 확인-앱 식별-정책 매칭의 4단계로 트래픽을 판정함

## Ⅳ. 문제점
- 암호화 사각: SSL/TLS 암호화 트래픽은 복호화 없이 L7 검사가 불가능함
- 성능 저하: DPI와 IPS 엔진 동시 가동 시 처리량(throughput)이 감소함
- 정책 복잡성: 앱 기반 수천 개 규칙이 누적되면 관리 오류와 규칙 충돌이 발생함

> 요약: 암호화 사각, 성능 부담, 정책 복잡성이 NGFW 운영의 핵심 과제임

## Ⅴ. 개선방안
1. 단기: SSL 복호화 전용 하드웨어 가속기를 도입하여 DPI 성능을 보전함
2. 중기: 정책 자동 최적화 도구로 미사용 규칙을 정리하고 충돌을 탐지함
3. 장기: 클라우드 네이티브 FWaaS(Firewall as a Service)로 전환하여 탄력적 확장을 확보함

> 요약: 하드웨어 가속, 정책 최적화, FWaaS 전환으로 방화벽의 한계를 극복함

## Ⅵ. 전망
- 발전 방향: SASE/SSE 내 FWaaS로 클라우드 기반 방화벽이 확산될 전망
- 기술사적 판단: 온프레미스 NGFW와 클라우드 FWaaS가 병행 운영되는 하이브리드 구조가 당분간 지속될 것임
- 기술사 제언: 멀티클라우드 환경에서 통합 정책 관리 체계를 수립하여 방화벽 규칙의 일관성을 확보해야 함
