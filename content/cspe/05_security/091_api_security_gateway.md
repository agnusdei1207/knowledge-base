## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | API 트래픽의 인증·인가·속도 제한·위협 탐지를 중앙에서 수행하는 보안 전문 게이트웨이임 |
| **배경/필요성** | 마이크로서비스 환경에서 API 수가 급증하며, 개별 서비스에 보안을 분산 구현하면 일관성·가시성이 저하됨 |
| **출제 의도** | API 게이트웨이의 보안 기능과 WAF·CASB와의 역할 구분을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 인증/인가 | --> | 속도제한  | --> | 위협탐지  |
| (AuthN/Z)|     | (Rate)   |     | (Threat) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 인증/인가 | OAuth·JWT·API Key 검증으로 호출자 신원과 권한을 확인함 | 건물 출입카드 검사 |
| 속도 제한 | IP·사용자별 요청 빈도를 제한하여 DDoS·크래딩 공격을 억제함 | 놀이공원 탑승 대기줄 |
| 위협 탐지 | OWASP API Top 10 패턴(인젝션, BOLA 등)을 실시간 분석·차단함 | 보안 CCTV 행동 분석 |

> 요약: 인증·속도 제한·위협 탐지를 중앙 게이트웨이에서 수행하여 API 보안을 일원화함.

## Ⅲ. 절차
```
+------------+     +------------+
| API요청    | --> | 게이트웨이 |
| 수신       |     | 인증검증   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 백엔드     | <-- | 정책적용  |
| 라우팅     |     | 위협분석   |
+------------+     +------------+
```

1. 요청 수신: 클라이언트의 API 호출이 게이트웨이로 인입됨
2. 인증·인가: JWT 서명 검증, OAuth 스코프 확인, API Key 유효성을 체크함
3. 정책 적용: Rate Limiting, IP 화이트리스트, 요청 크기 제한 등 보안 정책을 적용함
4. 위협 분석·라우팅: 인젝션·BOLA 패턴을 분석한 후 정상 요청만 백엔드 서비스로 전달함

> 요약: 수신 → 인증 → 정책 → 위협 분석 → 라우팅으로 API 트래픽을 보안 필터링함.

## Ⅳ. 문제점
- 단일 장애점: 모든 트래픽이 게이트웨이를 경유하므로 장애 시 전체 서비스가 중단됨
- 성능 병목: 복잡한 보안 정책 적용 시 응답 지연(Latency)이 증가함
- 섀도 API 미탐지: 게이트웨이를 우회하여 직접 노출된 비관리 API(섀도 API)가 공격면이 됨

## Ⅴ. 개선방안
- (단기) HA 이중화: Active-Active 구성으로 단일 장애점을 제거함
- (중기) API 자동 디스커버리: 트래픽 미러링으로 섀도 API를 자동 탐지·등록함
- (장기) AI 기반 이상 탐지: ML 모델이 정상 API 사용 패턴을 학습하여 이상 요청을 실시간 탐지함

## Ⅵ. 전망
- API 보안 게이트웨이에 AI 기반 BOLA·BFLA 탐지 엔진이 통합되며, OWASP API Security Top 10 대응이 자동화될 전망임
