## 미리 알고가기

- 특권 계정은 관리자처럼 시스템 설정과 데이터에 큰 영향을 주는 높은 권한 계정을 뜻함
- PAM은 이런 계정의 비밀번호 보관, 승인, 접속, 세션 기록, 자동 회전을 관리하는 체계임
- IAM이 전체 계정 생명주기를 다룬다면 PAM은 그중에서도 고위험 특권 접근을 더 엄격히 통제하는 영역임

## Ⅰ. 개요

- **정의/개념**: PAM은 관리자와 root와 서비스 관리자 같은 특권 계정의 자격 증명과 세션과 승인 절차를 중앙에서 통제해 오남용과 탈취 피해를 줄이는 보안 관리 체계임
- **배경/필요성**: 특권 계정 하나가 탈취되면 전체 시스템 장악과 데이터 변경이 가능해져 일반 계정보다 피해가 훨씬 크므로, 특권 사용 자체를 짧고 추적 가능하게 만들어야 함

## Ⅱ. 특징

- 특권 자격 증명을 금고에 보관하고 직접 노출을 줄일 수 있음
- 승인 기반 접근과 세션 녹화로 사후 책임 추적이 쉬워짐
- JIT나 JEA 방식으로 상시 권한을 줄일 수 있음
- 스크립트와 애플리케이션 비밀값까지 범위를 넓히지 않으면 일부 특권 경로가 남음

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 IAM | PAM |
|:---|:---|:---|
| 주 대상 | 전체 사용자와 서비스 계정 | 관리자와 고위험 특권 계정 |
| 핵심 기능 | 계정 생성, 인증, 권한 부여 | 금고, 승인, 세션 프록시, 회전 |
| 목적 | 일반 접근 관리 | 특권 오남용과 탈취 억제 |
| 적합 환경 | 조직 전반 기본 계정 관리 | 운영·DB·네트워크·클라우드 관리자 계정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Vault | 특권 자격 증명을 안전하게 저장하고 회전함 |
| Approval Workflow | 누가 왜 언제 접근하는지 승인 절차를 거침 |
| Session Proxy and Recording | 접속을 중계하고 명령과 화면을 기록함 |
| JIT/JEA | 필요한 시간과 범위만 특권을 부여함 |

```text
접근 요청 -> 승인 -> Vault 자격 증명 사용 -> 세션 중계/기록 -> 자동 회수/회전
```

## Ⅴ. 원리 및 절차 흐름도

```text
특권 요청 -> 승인 확인 -> 임시 세션 발급 -> 작업 수행/기록 -> 시간 만료 -> 비밀값 회전
```

1. **특권 요청**: 운영자가 시스템 접근을 신청함
2. **승인 확인**: 업무 목적과 시간과 대상 시스템을 검토함
3. **임시 세션 발급**: PAM이 비밀값을 대신 사용해 접속을 중계함
4. **작업 기록**: 명령과 화면과 시간 정보를 남김
5. **회수와 회전**: 작업 후 세션을 종료하고 비밀값을 갱신함

## Ⅵ. 실무 적용 및 유의점

1. 운영 DB와 네트워크 장비와 클라우드 관리자 계정은 PAM으로 직접 비밀번호 노출을 줄이고 임시 권한 부여(JIT)와 세션 기록과 자동 회전을 함께 적용한 뒤 상시 특권 계정 수 감소와 세션 기록 완전성으로 확인함
2. 스크립트와 배치 계정이 많은 환경은 사람 계정만 PAM에 넣지 말고 비밀값 관리와 서비스 계정까지 범위를 넓혀 하드코딩 자격 증명 제거율과 특권 계정 비밀값 회전 준수 여부로 확인함

## Ⅶ. 결론

- PAM은 특권 계정 사용을 짧고 추적 가능하게 만들어 관리자 권한 탈취와 오남용의 피해를 줄이는 핵심 통제임
