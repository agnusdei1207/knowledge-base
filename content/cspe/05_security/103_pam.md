## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | root·Administrator 등 최고 권한 계정의 자격증명을 금고에 보관하고, 접근 승인·세션 녹화·일회성 발급으로 특권 남용을 통제하는 보안 솔루션임 |
| **배경/필요성** | 특권 계정 탈취는 공격자에게 전체 시스템 장악을 허용하며, 내부자 위협의 80%가 특권 계정 오남용에서 기인함 |
| **출제 의도** | PAM의 핵심 기능(비밀번호 금고·세션 관리·JIT 접근)과 IAM과의 관계를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 비밀번호  | --> | 세션관리  | --> | JIT접근  |
| 금고     |     | (녹화)   |     | (일회성) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 비밀번호 금고 | 특권 계정의 자격증명을 암호화하여 중앙 금고에 보관하고, 주기적으로 자동 변경함 | 은행 대여 금고 |
| 세션 관리 | 특권 세션을 프록시하여 모든 명령어·화면을 녹화·감사함 | CCTV가 달린 금고실 |
| JIT 접근 | 필요 시 승인을 거쳐 제한된 시간 동안만 특권을 부여하고 자동 회수함 | 시간제 임시 출입증 |

> 요약: 금고(보관) → 세션(감시) → JIT(시한부 발급)로 특권 계정의 전 생명주기를 통제함.

## Ⅲ. 절차
```
+------------+     +------------+
| 접근신청   | --> | 워크플로우  |
| (관리자)   |     | 승인       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 자동회수   | <-- | 세션연결   |
| 비번변경   |     | 녹화시작   |
+------------+     +------------+
```

1. 접근 신청: 관리자가 PAM 포털에서 대상 시스템·작업 목적·소요 시간을 기재하여 신청함
2. 승인 워크플로우: 상급자·보안팀이 신청을 검토하고 승인·거부를 결정함
3. 세션 연결·녹화: PAM이 금고에서 자격증명을 체크아웃하여 프록시 세션을 열고, 모든 행위를 녹화함
4. 자동 회수: 승인된 시간이 만료되면 세션을 강제 종료하고, 비밀번호를 자동 변경(체크인)함

> 요약: 신청 → 승인 → 세션 녹화 → 자동 회수로 특권 접근을 최소 시간·최대 감시로 통제함.

## Ⅳ. 문제점
- 하드코딩 자격증명: 스크립트·설정파일에 하드코딩된 서비스 계정 비밀번호가 PAM 관리 범위 밖에 존재함
- 에이전트 미설치: 레거시 시스템에 PAM 에이전트 설치가 불가하여 사각지대가 발생함
- 클라우드 서비스 계정: AWS IAM Role·GCP Service Account 등 클라우드 네이티브 특권의 통합 관리가 어려움

## Ⅴ. 개선방안
- (단기) Secrets Manager 연동: 하드코딩된 자격증명을 Vault·AWS Secrets Manager로 이관하여 동적 발급함
- (중기) 에이전트리스 PAM: 네트워크 기반 프록시 방식으로 레거시 시스템의 특권 세션을 관리함
- (장기) CIEM+PAM 통합: 클라우드 IAM의 과도한 권한을 CIEM으로 탐지하고 PAM의 JIT로 최소화함

## Ⅵ. 전망
- Zero Standing Privileges(ZSP) 개념이 확산되어 상시 특권 계정을 제거하고, 모든 특권 접근을 JIT·JEA(Just Enough Access)로 전환하는 방향으로 발전할 전망임
