## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 여러 참여자가 서로의 입력 데이터를 상대방이나 제3자에게 절대 공개하지 않고, 오직 공동의 연산 결과만을 도출하는 암호 프로토콜임 |
| **배경/필요성** | 기업 간 데이터 결합 시 상호 불신 및 개인정보보호 규제로 인해 원본 데이터 공유가 불가능한 한계 극복 필요 |
| **출제 의도** | 비밀 분산(Secret Sharing)과 가블드 서킷(Garbled Circuit) 원리, 그리고 동형 암호와의 차이점 이해 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|   Secret Input    |      |  Secret Sharing   |      |  Joint Output     |
| (참여자별 비밀값) +----->| (조각내어 상호교환)+----->| (최종 연산 결과)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **비밀 분산 (Secret Sharing)** | 원본 데이터를 의미 없는 여러 조각(Share)으로 쪼개어 다른 참여자들에게 나누어 주는 기법임 | 보물지도 3조각으로 찢어 나눠 갖기 |
| **다자간 연산 프로토콜** | 나눠진 조각(Share)들을 기반으로 논리 회로나 수학적 덧셈/곱셈을 각자 수행한 후 결과를 합치는 과정임 | 각자 조각 안에서 퍼즐 맞추기 |
| **비밀성 (Privacy)** | 연산 도중이거나 끝난 후에도 상대방의 원본 데이터를 절대 역추산할 수 없는 성질임 | 합쳐진 퍼즐 모양만 보고 원본 유추 불가 |

> 요약: 신뢰할 수 없는 다수가 각자의 비밀을 조각내어 공유한 뒤 협력 계산하여 결괏값만 공유하는 체계임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 데이터 분할 |-->| 2. 조각 교환   |-->| 3. 로컬 연산   |-->| 4. 결과 병합   |
| (비밀 분산)    |   | (네트워크 전송)|   | (각자 분산 연산)|   | (최종값 도출)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **데이터 분할**: 각 참여자(Party)가 자신의 민감한 입력값을 비밀 분산 알고리즘(예: Shamir's Secret Sharing)을 이용해 여러 조각으로 나눔
2. **조각 교환**: 쪼개진 무의미한 데이터 조각들을 다른 모든 참여자에게 안전한 채널을 통해 서로 배포함
3. **로컬 연산**: 각 참여자는 자신이 받은 조각들만을 가지고 사전에 합의된 함수(가블드 서킷 등)에 따라 독자적인 연산을 수행함
4. **결과 병합**: 각자 계산된 부분 결괏값들을 다시 모아서 결합하여, 최종적으로 원하는 연산 결과를 도출함

> 요약: 원본 없이 쪼개진 정보만 교환하여 각자 계산을 수행한 후 퍼즐을 맞추듯 최종 결과만 완성함.

## Ⅳ. 문제점
* **통신 오버헤드 과다**: 연산 과정의 매 단계마다 참여자 간 데이터를 주고받아야 하므로 엄청난 네트워크 대역폭과 통신 지연 발생
* **참여자 간 담합(Collusion) 취약성**: 다수의 참여자가 서로 공모하여 각자의 조각을 맞춰보면 다른 선의의 참여자 데이터가 노출될 위험 존재
* **동기화 및 단일 이탈 문제**: 한 참여자라도 오프라인이 되거나 악의적으로 잘못된 값을 보내면 전체 연산이 중단되거나 오염됨

## Ⅴ. 개선방안
* **단기 방안 (정직한 다수 가정 설정)**: 악의적 공격자를 1명 이하로 가정하는 등 실용적인 보안 모델(Semi-honest)을 적용해 연산 효율성 최적화
* **중기 방안 (통신 라운드 최소화)**: 통신 횟수를 줄이기 위해 전처리 단계(Offline phase)에서 무거운 난수 생성 작업을 미리 끝내고, 실제 온라인 연산 속도 향상
* **장기 방안 (악의적 모델 방어)**: 영지식 증명(ZKP)이나 MAC을 MPC 과정에 결합하여 누군가 악의적 변조를 시도하더라도 즉각 탐지하고 배제하는 강건한(Malicious) 프로토콜 구현

## Ⅵ. 전망
* 데이터3법 등 프라이버시 규제가 강화됨에 따라 의료 기관의 질병 예측, 금융 기관의 연합 신용평가 등 '데이터 연합(Data Federation)'의 핵심 솔루션으로 부각됨
* 동형 암호는 서버 1대에 위탁하는 구조라면, MPC는 여러 기관이 평등하게 분산 계산하는 구조로서 적용 비즈니스 환경에 따라 상호 보완적으로 성장할 것임
