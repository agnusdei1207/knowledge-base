## 미리 알고가기

- 연속 인증은 로그인 한 번으로 끝내지 않고 세션 중에도 사용자의 신뢰 수준을 계속 재평가하는 방식임
- 입력 패턴, 위치 변화, 단말 상태, 요청 행동 같은 신호를 모아 이상 징후를 찾음
- 목적은 사용자를 계속 괴롭히는 것이 아니라 세션 탈취와 대리 사용을 빨리 알아차리는 데 있음

## Ⅰ. 개요

- **정의/개념**: 연속 인증·동적 신뢰 평가는 로그인 이후에도 사용자 행위, 단말 상태, 접속 맥락을 수집해 세션 신뢰도를 갱신하는 방식임
- **배경/필요성**: MFA 통과 후에도 세션 하이재킹, AiTM, 내부 오남용이 가능함. 초기 인증만으로 세션 전체를 신뢰하기 어려움

## Ⅱ. 특징

- 한 번 허용된 세션도 위험 점수에 따라 다시 제한할 수 있음
- 사용자 위치, 기기, 행동 패턴이 평가 재료가 됨
- 오탐이 많으면 사용자 불편과 업무 중단이 커져 임계값 조정이 중요함
- 프라이버시와 설명 가능성을 고려하지 않으면 현장 수용성이 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 1회성 인증 | 연속 인증 |
|:---|:---|:---|
| 신뢰 판단 시점 | 로그인 시점 | 로그인 이후 세션 전반 |
| 장점 | 단순하고 사용자 마찰이 적음 | 세션 탈취와 이상 행위 대응이 빠름 |
| 한계 | 로그인 후 탈취 탐지가 약함 | 오탐과 데이터 수집 부담이 있음 |
| 적합 환경 | 일반 저위험 서비스 | 관리자 세션, 중요 업무 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Telemetry Collection | 행위와 위치와 단말 상태를 수집함 |
| Risk Engine | 수집 신호를 기반으로 신뢰 점수를 계산함 |
| Response Logic | Step-up 인증, 세션 축소, 차단을 수행함 |
| Audit and Tuning | 오탐과 미탐을 분석해 정책을 조정함 |

```text
초기 인증 -> 세션 중 신호 수집 -> 위험 점수 재평가 -> 추가 인증/차단 -> 로그와 튜닝
```

## Ⅴ. 원리 및 절차 흐름도

```text
로그인 성공 -> 행동/컨텍스트 수집 -> 기준선과 비교 -> 점수 하락 시 대응 -> 세션 유지 또는 종료
```

1. **로그인 성공**: 기본 인증과 MFA로 세션이 시작됨
2. **신호 수집**: 위치와 단말과 행동과 API 사용 패턴을 수집함
3. **기준선 비교**: 평소 패턴과 차이를 평가함
4. **대응 실행**: 점수가 낮아지면 Step-up 인증이나 차단을 수행함
5. **정책 조정**: 오탐과 우회 사례를 반영해 재조정함

## Ⅵ. 실무 적용 및 유의점

1. 관리자 콘솔·금융 거래는 추가 인증 기준과 세션 축소 정책을 명확히 하고 세션 탈취 탐지율과 오탐 업무 중단 비율로 확인함
2. 사용자 서비스는 필요한 신호만 최소 수집하고 수집 항목 최소화, 정책 설명 가능성, 추가 인증 빈도로 확인함

## Ⅶ. 결론

- 연속 인증은 로그인 이후 세션도 계속 검증 대상으로 두어 세션 탈취와 대리 사용을 더 빨리 줄이는 제로 트러스트 보완 수단임
