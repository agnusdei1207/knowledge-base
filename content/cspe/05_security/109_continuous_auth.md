## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 로그인 시점의 1회 인증에 의존하지 않고, 세션 중 사용자의 행위·생체·컨텍스트를 지속 분석하여 신뢰 수준을 동적으로 평가하는 인증 방식임 |
| **배경/필요성** | 세션 하이재킹·AiTM 공격으로 초기 인증 이후 탈취가 가능하며, 세션 전체에 걸친 지속적 신원 보증이 필요함 |
| **출제 의도** | 연속 인증의 동작 원리와 Step-up 인증 트리거 조건을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 행위분석  | --> | 신뢰점수  | --> | 적응조치  |
| (UEBA)   |     | (Score)  |     | (Step-up)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 행위 분석 | 키스트로크·마우스 패턴·네비게이션 습관 등을 ML 모델로 지속 분석함 | 필체 감정사 |
| 신뢰 점수 | 행위·컨텍스트·디바이스 상태를 종합하여 0~100 실시간 Trust Score를 산출함 | 체온계(이상 시 알람) |
| 적응 조치 | Score 저하 시 Step-up 인증 요구·세션 제한·강제 로그아웃 등을 수행함 | 수상 시 재신분 확인 |

> 요약: 행위 분석(지속 모니터링) → 신뢰 점수(동적 평가) → 적응 조치(리스크 대응)로 세션 보안을 유지함.

## Ⅲ. 절차
```
+------------+     +------------+
| 초기인증   | --> | 행위수집   |
| (로그인)   |     | (지속분석) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 적응조치   | <-- | 신뢰점수  |
| (Step-up)  |     | 실시간산출 |
+------------+     +------------+
```

1. 초기 인증: MFA를 통해 로그인하고 기본 세션을 생성함
2. 행위 데이터 수집: 세션 중 키 입력 패턴·마우스 움직임·앱 전환·API 호출 패턴을 수집함
3. 신뢰 점수 실시간 산출: ML 모델이 행위 기준선(Baseline)과 비교하여 이상 정도를 점수화함
4. 적응 조치: 점수가 임계치 이하로 하락하면 Step-up 인증 요구·세션 범위 축소·강제 종료를 수행함

> 요약: 로그인 → 행위 수집 → 점수 산출 → 적응 조치로 세션 중 지속 보증을 제공함.

## Ⅳ. 문제점
- 프라이버시 우려: 키 입력·화면 활동 등 민감 행위 데이터 수집에 대한 개인정보 이슈가 있음
- 오탐 문제: 정상 사용자의 행위 변화(새 키보드·급한 업무)를 이상으로 오탐할 수 있음
- 성능 부담: 실시간 행위 분석 ML 모델의 연산 부하가 클라이언트·서버에 영향을 줄 수 있음

## Ⅴ. 개선방안
- (단기) 데이터 최소 수집: 인증에 필요한 최소한의 행위 특성만 수집하여 프라이버시를 보호함
- (중기) 학습 기간 확보: 충분한 Baseline 학습 기간을 두어 오탐율을 줄이고, 점진적으로 정책을 강화함
- (장기) 온디바이스 ML: 행위 분석을 디바이스 로컬에서 수행하여 서버 전송 없이 프라이버시를 보장함

## Ⅵ. 전망
- 제로 트러스트 환경에서 연속 인증이 세션 보안의 핵심으로 부상하며, 온디바이스 AI 분석과 결합하여 사용자 마찰 없는 투명 인증(Transparent Authentication)이 실현될 전망임
