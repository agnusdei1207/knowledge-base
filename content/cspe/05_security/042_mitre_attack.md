## 미리 알고가기

- ATT&CK은 공격자의 실제 전술과 기법과 절차를 지식베이스 형태로 정리한 프레임워크임
- 킬체인이 단계 흐름 설명에 강하다면 ATT&CK은 세부 탐지 설계와 커버리지 분석에 강함
- 단순 나열보다 자사 탐지 로그와 방어 통제를 어떤 기술에 매핑할지가 중요함

## Ⅰ. 개요

- **정의/개념**: MITRE ATT&CK은 실제 침해 사례에서 관찰된 공격자의 전술과 기법과 절차를 체계적으로 정리해 탐지, 헌팅, 모의훈련, 보안 통제 평가에 활용하는 지식 프레임워크임
- **배경/필요성**: 보안 장비별 경보만으로는 공격자의 전체 행위를 설명하기 어려워 공통 언어로 TTP를 표현하고 탐지 커버리지를 비교할 기준이 필요함

## Ⅱ. 특징

- 전술과 기법과 서브기법으로 구조화돼 탐지 규칙과 공격 행위를 세밀하게 연결할 수 있음
- 벤더 제품이 달라도 공통 TTP ID로 탐지 결과와 방어 범위를 비교할 수 있음
- Threat hunting, purple teaming, SOC 룰 튜닝의 공통 기준으로 활용하기 좋음
- 기법을 많이 매핑했다고 방어가 완성되는 것은 아니므로 데이터 소스와 대응 플레이북까지 함께 점검해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Cyber Kill Chain | MITRE ATT&CK |
|:---|:---|:---|
| 주 관점 | 공격 진행 단계 | 전술·기법·절차 |
| 강점 | 흐름과 차단 지점 설명 | 세부 탐지와 헌팅 설계 |
| 대표 활용 | 침해 분석 서사 | 커버리지 매핑과 규칙 설계 |
| 대표 한계 | 세부 기법 표현이 단순함 | 우선순위 없이 나열하면 운영 부담이 커짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Tactics | 공격자가 달성하려는 상위 목적이며 초기 접근, 실행, 지속성, 유출 같은 행위 목적을 나타냄 |
| Techniques and Sub-techniques | 각 전술을 수행하는 구체 수단으로 탐지 규칙과 로그 소스를 연결하는 핵심 단위임 |
| Data Sources | 프로세스 실행, 인증 로그, 네트워크 흐름처럼 기법을 확인할 수 있는 관측 근거 계층임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 위협 시나리오 선정 | -> | TTP 매핑      | -> | 데이터 소스 연결 | -> | 탐지 규칙 작성  | -> | 훈련/보완      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **위협 시나리오 선정**: 조직에 중요한 공격 시나리오와 자산을 정함
2. **TTP 매핑**: 관련 전술과 기법과 서브기법을 식별함
3. **데이터 소스 연결**: 각 기법을 확인할 로그와 텔레메트리를 매핑함
4. **탐지 규칙 작성**: SIEM, EDR, NDR 규칙과 플레이북으로 구현함
5. **훈련과 보완**: purple team과 헌팅 결과로 누락 구간을 보완함

## Ⅵ. 실무 적용 및 유의점

1. SOC와 탐지 엔지니어링 팀은 ATT&CK 매트릭스로 규칙 커버리지를 관리하기 좋지만 고위험 자산 기준 우선순위가 없으면 룰만 늘어나므로 핵심 전술부터 단계적으로 매핑하고 전술별 커버리지와 실제 탐지율과 오탐률로 확인함
2. 모의해킹과 purple teaming은 ATT&CK 기반 시나리오 설계에 적합하지만 로그 수집 범위가 부족하면 매핑만 존재하고 검증이 안 되므로 데이터 소스 점검과 플레이북 검증을 함께 수행하고 미탐 기법 수와 보완 완료율로 확인함

## Ⅶ. 결론

- MITRE ATT&CK은 공격자의 세부 행위를 공통 언어로 정리하는 프레임워크이므로 자사 자산과 로그와 대응 체계에 매핑될 때 비로소 실무 가치가 생김
