## Ⅰ. 개요
- **정의**: 외부 보안 연구자가 취약점을 발견·신고하면 보상금을 지급하는 프로그램
- **배경/필요성**: 내부 보안 인력만으로는 다양한 공격 시나리오를 커버하기 어려워 크라우드소싱이 필요함
- **비유**: 현상금 수배처럼 외부 전문가에게 보안 허점 발견을 의뢰하는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로그램 설계·운영 체계 | 범위 정의·보상 기준·책임 면책 | 모의침투 테스트(047 참조)와 차이 구분 |

> 요약: 외부 연구자의 집단 지성을 활용하여 취약점 발견 범위를 확대하는 프로그램임

## Ⅱ. 구성요소
```text
+-----------+     +----------+     +---------+     +--------+
| Policy    | --> | Researcher| --> | Triage  | --> | Reward |
| & Scope   |     | Community |     | Team    |     | Payout |
+-----------+     +----------+     +---------+     +--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 정책·범위(Policy) | 대상 자산·규칙·면책 조건을 공개 정의 | 현상금 수배 공고 |
| 연구자 커뮤니티 | 등록된 외부 보안 전문가 풀 | 현상금 사냥꾼 |
| 트리아지 팀 | 신고된 취약점의 유효성·심각도를 검증하는 내부 팀 | 신고 접수 심사관 |

> 요약: 정책-연구자-트리아지-보상의 구조로 취약점 수집 파이프라인을 구성함

## Ⅲ. 절차
```text
프로그램 설계 -> 취약점 수집 -> 트리아지 검증 -> 보상 지급
```
- 1단계: 대상 범위·보상 기준·법적 면책 조건을 포함한 정책 설계
- 2단계: 외부 연구자가 취약점을 발견하고 플랫폼을 통해 신고
- 3단계: 트리아지 팀이 재현·심각도 평가 후 유효 취약점 확정
- 4단계: 심각도에 비례한 보상금 지급 및 취약점 패치 수행

> 요약: 정책 설계부터 보상 지급까지 4단계로 외부 취약점 수집을 운영함

## Ⅳ. 문제점
- 중복 신고 과다: 동일 취약점이 다수 신고 — 트리아지 팀 업무 부하 증가
- 범위 외 테스트: 연구자가 범위를 벗어나 테스트 — 서비스 장애·법적 분쟁 가능
- 보상 기준 불명확: 심각도 판정에 이견 발생 — 연구자 신뢰 저하 및 이탈

> 요약: 중복 신고·범위 이탈·보상 기준 모호성이 프로그램 효율을 저해함

## Ⅴ. 개선방안
1. 단기: 자동 중복 탐지 시스템 도입으로 트리아지 부하 감소
2. 중기: 명확한 범위 명세와 Safe Harbor 조항으로 법적 리스크 최소화
3. 장기: CVSS 기반 투명한 보상 매트릭스를 공개하여 연구자 신뢰 확보

> 요약: 중복 탐지·법적 보호·투명 보상으로 프로그램의 지속 가능성을 확보함

## Ⅵ. 전망
- 발전 방향: VDP(Vulnerability Disclosure Policy)와 연계된 상시 운영이 표준화될 것임
- 기술사적 판단: 내부 보안 역량과 외부 크라우드소싱의 병행이 최적 전략임
- 기술사 제언: 버그 바운티를 모의침투 테스트의 보완 수단으로 위치시킬 것을 제언함
