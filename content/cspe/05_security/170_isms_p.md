## 미리 알고가기

- ISMS는 정보보호 관리체계이고, ISMS-P는 여기에 개인정보보호 요구를 함께 포함한 통합 인증임
- 관리체계는 보안 장비 몇 개를 두는 수준이 아니라 정책, 책임, 위험관리, 운영 증적을 반복 관리하는 구조임
- 인증 범위는 심사를 받는 서비스와 시스템과 조직 경계를 뜻하며 인증 실효성에 직접 영향을 줌

## Ⅰ. 개요

- **정의/개념**: ISMS-P는 정보보호와 개인정보보호를 위한 관리체계가 인증 기준에 맞게 수립되고 운영되는지를 외부 심사로 확인하는 국내 통합 인증 제도임
- **배경/필요성**: 서비스 규모가 커질수록 개별 보안 기술만으로는 사고를 막기 어렵고, 조직 전체가 정책과 책임과 운영 증적을 함께 관리해야 하므로 객관적인 점검 체계가 필요해짐

## Ⅱ. 특징

- 정보보호와 개인정보보호를 한 체계로 묶어 이중 관리 부담을 줄이면서도 범위를 넓게 다룸
- 기술 조치보다 관리체계 운영과 지속 개선 여부를 더 중요하게 봄
- 인증을 받더라도 범위를 너무 좁게 잡으면 실제 보호 수준과 괴리가 생길 수 있음
- 의무 대상 조직에는 규제 대응 의미가 크고, 임의 신청 조직에는 대외 신뢰 확보 수단이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | ISMS | ISMS-P |
|:---|:---|:---|
| 초점 | 정보보호 관리체계 전반 | 정보보호와 개인정보보호를 함께 다룸 |
| 개인정보 처리 단계 | 간접적으로만 반영됨 | 수집, 이용, 제공, 보관, 파기 요구를 직접 반영함 |
| 활용 환경 | 일반 정보보호 체계 구축에 적합함 | 개인정보를 많이 다루는 서비스에 더 적합함 |
| 실무 부담 | 보호조치 중심으로 구성하기 쉬움 | 개인정보 처리 절차와 증적까지 함께 챙겨야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 인증 범위 | 어떤 서비스와 시스템과 조직을 심사 대상에 넣을지 정하는 경계로, 실효성 판단의 출발점임 |
| 위험관리와 거버넌스 | 정책, 책임자, 자산 식별, 위험 평가, 개선 활동을 반복하게 하는 운영 뼈대임 |
| 보호대책 | 접근 통제, 암호화, 로그, 물리 보안, 인적 보안처럼 실제 방어 조치를 포함함 |
| 개인정보 처리 통제 | 동의, 제공, 위탁, 보유 기간, 파기 같은 개인정보 생명주기 통제를 포함함 |
| 심사와 증적 | 운영 명세서, 로그, 교육 기록, 점검 결과처럼 심사에서 확인하는 증거 집합임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 범위 정의      | -> | 위험과 정책    | -> | 보호대책 운영   | -> | 심사와 개선    |
+-------------+    +-------------+    +-------------+    +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 범위 설정      | -> | 위험 평가      | -> | 통제 구현      | -> | 심사 대응      | -> | 유지와 개선    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **범위 설정**: 서비스와 자산과 조직 범위를 정해 심사 경계를 분명히 함
2. **위험 평가**: 주요 자산과 위협과 취약점을 분석해 필요한 통제를 도출함
3. **통제 구현**: 정보보호 조치와 개인정보 처리 절차를 실제 운영에 반영함
4. **심사 대응**: 증적을 준비하고 외부 심사에서 적합성과 결함을 확인받음
5. **유지와 개선**: 시정 조치를 마치고 변경 사항을 계속 반영해 인증을 유지함

## Ⅵ. 실무 적용 및 유의점

1. 인증 준비 조직은 핵심 서비스와 연계 시스템을 범위에서 빠뜨리지 말고 범위 포함 비율과 중대 결함 건수로 인증 실효성을 확인함
2. 인증 취득 뒤에도 시스템 변경과 위탁 구조 변경을 즉시 반영해야 하므로 시정 조치 지연 건수와 연간 심사 지적 추세를 계속 관리함

## Ⅶ. 결론

ISMS-P는 보안 장비 목록을 확인하는 인증이 아니라 조직의 정보보호와 개인정보보호 운영 체계를 검증하는 인증이므로 범위와 증적과 지속 개선이 핵심임.
