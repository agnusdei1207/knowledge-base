## Ⅰ. 개요
- **정의**: 네트워크·호스트 트래픽을 감시하여 침입을 탐지(IDS)하거나 차단(IPS)하는 시스템임
- **배경/필요성**: 방화벽(021 참조)은 허용된 트래픽 내부의 공격 패턴을 식별하지 못하므로 별도 탐지·차단 계층이 필요함
- **비유**: CCTV(IDS)는 이상 행위를 녹화·알림하고, 자동 잠금장치(IPS)는 즉시 차단하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IDS와 IPS의 배치·동작 차이 | 미러링(탐지) vs 인라인(차단) 구조 | 오탐(FP)·미탐(FN) 개념 구분 필요 |

> 요약: 허용된 트래픽 내 공격 패턴을 시그니처·행위 분석으로 탐지·차단하는 시스템임

## Ⅱ. 구성요소
```text
Network Traffic --+--> [ IDS Sensor ] --> Alert --> SIEM
                  |
                  +--> [ IPS Engine ] --> Allow/Drop --> Destination
                            |
                            v
                     Signature DB + Anomaly Model
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Signature DB | 알려진 공격 패턴을 정의한 룰셋으로 패턴 매칭에 사용됨 | 수배 전단지 |
| Anomaly Model | 정상 트래픽 기준선 대비 편차를 탐지하는 행위 분석 모델임 | 평소와 다른 행동 감지 |
| Sensor/Engine | 트래픽을 캡처·분석하여 탐지(IDS) 또는 차단(IPS) 수행함 | 검문소 검사관 |
| Alert Manager | 탐지 이벤트를 분류·우선순위화하여 관제 시스템에 전달함 | 경보 분류 담당자 |

> 요약: 시그니처·이상 탐지 모델과 센서·경보 관리로 침입을 탐지·차단함

## Ⅲ. 절차
```text
트래픽 캡처 --> 시그니처 매칭 --> 이상 행위 분석 --> 대응(경보/차단)
```
- 1단계: 네트워크 탭/스팬 포트(IDS) 또는 인라인(IPS) 방식으로 트래픽을 캡처함
- 2단계: Signature DB와 패턴 매칭하여 알려진 공격 여부를 판정함
- 3단계: 시그니처 미매칭 트래픽에 대해 Anomaly Model로 비정상 행위를 분석함
- 4단계: 탐지 결과에 따라 경보 발생(IDS) 또는 패킷 차단(IPS)을 수행함

> 요약: 트래픽 캡처 후 시그니처·이상 분석을 거쳐 경보 또는 차단을 수행함

## Ⅳ. 문제점
- 오탐(False Positive): 시그니처 과잉 매칭으로 정상 트래픽을 공격으로 판정하여 업무 지장을 초래함
- 미탐(False Negative): 시그니처 미보유 신종 공격(Zero-Day)을 탐지하지 못함
- 암호화 트래픽 한계: TLS 암호화 페이로드 내부 패턴을 검사하지 못하여 사각지대가 발생함

> 요약: 오탐·미탐·암호화 미검사가 IDS/IPS의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 시그니처 튜닝·화이트리스트를 적용하여 오탐률을 감소시킴
2. 중기: ML 기반 행위 분석 모델을 도입하여 Zero-Day 탐지 능력을 향상함
3. 장기: SSL 복호화 장비·NGFW(022 참조) 연동으로 암호화 트래픽 가시성을 확보함

> 요약: 시그니처 튜닝, ML 행위 분석, 복호화 연동으로 탐지 정확도를 개선함

## Ⅵ. 전망
- 발전 방향: 독립 장비에서 NGFW·NDR(026 참조)·XDR(027 참조) 기능으로 흡수·통합되는 추세임
- 기술사적 판단: 네트워크 IDS/IPS 단독 운영보다 다계층 연계 분석이 탐지 효과를 높임
- 기술사 제언: IDS/IPS를 SIEM(028 참조)·SOAR(029 참조)와 연동한 자동 대응 체계 구축이 필요함
