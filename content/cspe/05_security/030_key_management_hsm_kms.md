## 미리 알고가기

- 루트 키: 다른 키를 보호하는 상위 키이며 조직의 암호 통제권을 대표함
- 데이터 키: 실제 데이터를 암호화하는 하위 대칭키임
- Envelope Encryption: 데이터는 데이터 키로 암호화하고, 데이터 키는 루트 키로 다시 감싸는 방식임
- Zeroization: 키를 메모리나 장비에서 복구 불가능하게 완전히 삭제하는 절차임

## Ⅰ. 개요

- **정의/개념**: 키 관리는 암호키의 생성, 저장, 배포, 사용, 교체, 폐기까지 전 생명주기를 통제하는 체계이며, HSM은 키를 보호하는 하드웨어 기반 금고이고 KMS는 키 정책과 사용 절차를 운영하는 관리 시스템임
- **배경/필요성**: 실제 사고의 많은 원인은 알고리즘이 아니라 키 노출, 하드코딩, 권한 오남용이므로, 암호 자체보다 키를 어디에 두고 누가 어떻게 쓰는지 통제하는 체계가 필요함

## Ⅱ. 특징

- 강한 암호도 키 관리가 약하면 전체 보호가 무너지므로 키 생명주기 거버넌스가 암호 시스템의 핵심임
- HSM은 키 추출을 막고 민감 연산을 장비 안에서 처리하는 데 강하며, KMS는 대량 키 운영과 정책 자동화에 강함
- 데이터 키와 루트 키를 분리하면 대용량 데이터를 빠르게 처리하면서도 루트 키 통제권을 유지할 수 있음
- 클라우드 환경에서는 편의성과 데이터 주권 사이 균형 때문에 BYOK, 외부 키 저장소 같은 추가 설계가 자주 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | HSM | KMS |
|:---|:---|:---|
| 주 역할 | 키 생성과 서명·암복호화 같은 민감 연산을 장비 안에서 보호함 | 키 정책, 접근 제어, 회전, 감사 로그를 중앙에서 관리함 |
| 보호 방식 | 물리적 변조 대응과 추출 방지에 강함 | API와 IAM 기반 운영 통제에 강함 |
| 운영 범위 | 소수의 루트 키나 고신뢰 연산 처리에 맞음 | 많은 애플리케이션과 데이터 키를 대규모로 운영하기에 맞음 |
| 실무 선택 | 결제, PKI, 루트 서명처럼 키 노출 자체가 치명적일 때 맞음 | 클라우드 스토리지, 데이터베이스, 서비스 간 공통 키 운영에 맞음 |

> 요약: HSM은 키를 지키는 금고이고, KMS는 그 금고를 어떤 정책으로 쓸지 운영하는 통제 계층임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 루트 키 | 데이터 키를 보호하는 상위 키이며 노출되면 하위 키 전부가 위험해지므로 가장 강한 보호가 필요함 |
| 데이터 키 | 실제 파일이나 레코드를 암호화하는 하위 키이며 대량 생성과 회전이 자주 일어남 |
| HSM | 루트 키를 생성하고 추출 없이 연산하는 물리 또는 논리 보안 모듈임 |
| KMS 정책 계층 | 어떤 서비스와 사용자가 어떤 키를 언제 쓸 수 있는지 통제하고 감사 로그를 남기는 운영 계층임 |

```text
+--------+     +---------+     +-----------+     +----------+
| HSM    | --> | 루트 키  | --> | 데이터 키  | --> | 실제 데이터 |
+--------+     +---------+     +-----------+     +----------+
                    ^
                    |
               +---------+
               | KMS 정책 |
               +---------+
```

> 요약: HSM이 루트 키를 보호하고, KMS가 정책으로 데이터 키 사용을 통제하는 계층 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +----------+     +----------+     +----------+     +----------+
| 키 생성  | --> | 키 배포  | --> | 데이터 암호화 | --> | 키 회전  | --> | 키 폐기  |
+----------+     +----------+     +----------+     +----------+     +----------+
```

1. **키 생성**: 루트 키와 데이터 키를 신뢰 가능한 난수원으로 생성함
2. **키 배포**: 허가된 서비스에만 필요한 범위로 키를 전달함
3. **데이터 암호화**: 데이터 키로 실제 데이터를 처리하고 루트 키로 데이터 키를 감쌈
4. **키 회전**: 주기나 사고 기준에 따라 새 키로 바꾸고 기존 데이터를 재보호함
5. **키 폐기**: 만료되거나 노출된 키를 복구 불가능하게 삭제함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 스토리지와 데이터베이스 암호화에서는 envelope encryption이 현실적이지만 CSP 관리 키만 쓰면 통제권이 약해질 수 있으므로 BYOK나 외부 키 저장소를 함께 검토하고 키 사용 로그, 회전 주기 준수율, 비인가 호출 차단 건수로 확인함
2. 결제 시스템이나 루트 CA 서명처럼 키 노출 비용이 극단적으로 큰 환경에서는 HSM과 이중 승인 절차가 필수이며 운영자가 편의상 우회 저장을 하지 못하게 절차를 강제하고 서명 지연, 감사 로그 완전성, zeroization 점검 결과로 확인함

## Ⅶ. 결론

키 관리의 본질은 암호 알고리즘보다 통제권과 운영 절차를 지키는 데 있으므로, 실무에서는 HSM과 KMS를 역할에 맞게 나누고 키 생명주기 전체를 감사 가능하게 만드는 것이 핵심임.
