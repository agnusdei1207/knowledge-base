## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 고정된 길이(예: 128비트)를 처리하는 블록 암호 알고리즘(AES 등)을 이용해 그보다 긴 대용량 평문을 암호화하는 방법론임 |
| **배경/필요성** | 동일한 평문 블록이 동일한 암호문으로 변환되는 취약점(ECB 모드)을 해결하고, 다양한 네트워크 전송 특성에 맞춘 적용 방식 필요 |
| **출제 의도** | 각 모드(CBC, CTR)의 연관성(체인) 원리와 최신 인증 결합 모드(GCM)의 병렬 처리 특성 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  IV (Init Vector) |      |   Block Cipher    |      |  Chaining / XOR   |
| (초기 무작위 벡터)+----->|  (AES 엔진 연산)  +----->| (블록 간 상태 결합)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **초기화 벡터 (IV/Nonce)** | 암호화 시작 시 매번 달라지는 임의의 난수로, 동일 평문도 다른 암호문으로 시작하게 만듦 | 요리 시작 전 뿌리는 무작위 조미료 |
| **블록 암호 엔진** | 평문이나 카운터를 키를 통해 암호화하는 핵심 수학 함수(AES 등)임 | 정해진 크기만 찍어내는 기계 틀 |
| **운영 모드 (CBC/CTR 등)** | 앞 블록의 결과를 뒤 블록에 섞거나(CBC), 숫자를 증가시켜(CTR) 연속 처리하는 논리적 흐름도임 | 기계들을 일렬로 묶거나 병렬로 세우는 방식 |

> 요약: 고정 틀을 가진 암호 엔진에 무작위성과 처리 순서의 논리를 더해 거대한 데이터를 연속적으로 암호화함.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. CBC 모드    |-->| 2. CTR 모드    |-->| 3. GCM 모드    |-->| 4. 모드 선택   |
| (체인식 종속성)|   | (카운터 병렬화)|   | (CTR + GMAC)   |   | (환경별 최적화)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **CBC (Cipher Block Chaining)**: 이전 블록의 암호문을 다음 블록 평문과 XOR한 후 암호화하여 블록 간 종속성(체인)을 형성함 (순차 연산)
2. **CTR (Counter)**: 1씩 증가하는 카운터 값을 암호화하여 키 스트림을 만들고 이를 평문과 XOR하여 처리함 (독립 병렬 연산 가능)
3. **GCM (Galois/Counter Mode)**: CTR 모드의 병렬 암호화 특성에 갈루아 필드 곱셈 기반의 MAC(인증 태그)을 결합해 기밀성과 무결성을 동시 확보함(AEAD)
4. **적용 및 최적화**: 데이터의 크기, 하드웨어 성능, 병렬 처리 요구사항에 맞춰 최적의 운영 모드(현재는 GCM 권장)를 선택 적용함

> 요약: 데이터를 엮는 방식(CBC)에서 벗어나 병렬 처리(CTR)를 거쳐 인증까지 통합(GCM)하는 진화 과정을 거침.

## Ⅳ. 문제점
* **CBC 패딩 오라클 공격**: 데이터 길이를 블록 배수로 맞추기 위한 패딩 구조의 오류 메시지를 분석해 암호문을 역추적하는 치명적 공격 존재
* **CBC 병렬 처리 불가**: 앞 블록의 결과가 나와야 다음 블록을 연산할 수 있어 멀티코어 환경에서 암호화 속도 저하 발생
* **CTR/GCM의 IV 재사용 위험**: 난수(IV/Nonce)가 재사용될 경우 키 스트림이 동일해져 평문이 노출되고 인증 태그(GCM) 기능도 완전히 붕괴됨

## Ⅴ. 개선방안
* **단기 방안 (GCM 전환 및 패딩 제거)**: TLS 설정에서 취약한 CBC 모드 제품군을 강제 비활성화하고, 패딩이 필요 없는 AES-GCM으로 전면 교체
* **중기 방안 (엄격한 Nonce 카운터 관리)**: 난수 생성 시 중복을 피하기 위해 단순 랜덤이 아닌 글로벌 동기화된 64비트 순차 카운터를 사용하여 재사용 원천 차단
* **장기 방안 (SIV-Mode 도입)**: 난수 재사용 시에도 보안 붕괴를 막아주는 오용 저항성(Misuse-resistant)이 결합된 최신 AES-GCM-SIV 운영 모드 도입

## Ⅵ. 전망
* TLS 1.3에서 CBC 등 구형 운영 모드를 표준에서 완전히 퇴출시키고, 오직 GCM 기반의 AEAD 모드만을 유일한 표준으로 채택함
* 향후 대용량 데이터베이스 암호화, 클라우드 스토리지, 고속 VPN 트래픽 보호 등 모든 산업군에서 병렬 처리가 가능한 인증 암호(GCM 등)가 독점적 지위를 유지함
