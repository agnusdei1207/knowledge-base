## Ⅰ. 개요
- **정의**: 웹 페이지에 악성 스크립트를 삽입하여 사용자 브라우저에서 실행시키는 공격
- **배경/필요성**: 사용자 입력이 검증 없이 HTML에 반영되면 세션 탈취, 피싱 등 클라이언트 측 피해가 발생함
- **비유**: 게시판에 몰래 함정을 설치하여 방문자가 밟게 하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 웹 취약점 유형 구분 | Stored/Reflected/DOM 3유형 차이 | 서버측 vs 클라이언트측 발생 지점 구분 |

> 요약: XSS는 입력값이 무검증으로 렌더링될 때 브라우저에서 악성 코드가 실행되는 공격임

## Ⅱ. 구성요소
```text
공격자 --악성스크립트--> 취약 웹서버 --응답--> 피해자 브라우저
                                                  |
                                                  v
                                          쿠키/세션 탈취
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Stored XSS | 악성 스크립트가 DB에 저장되어 모든 방문자에게 실행됨 | 건물에 설치된 영구 함정 |
| Reflected XSS | URL 파라미터에 포함된 스크립트가 응답에 반사되어 실행됨 | 우편물에 숨긴 1회성 함정 |
| DOM-based XSS | 서버 미경유, 클라이언트 JS가 DOM을 조작하여 실행됨 | 브라우저 내부에서 자체 발화 |

> 요약: XSS는 저장형, 반사형, DOM 기반으로 분류되며 발생 지점과 지속성이 다름

## Ⅲ. 절차
```text
입력 삽입 --> 서버/DOM 반영 --> 브라우저 렌더링 --> 스크립트 실행
```
- 1단계: 입력 삽입 — 공격자가 `<script>` 태그 등 악성 페이로드를 입력 필드나 URL에 삽입함
- 2단계: 서버/DOM 반영 — 입력값이 이스케이프 없이 HTML 응답 또는 DOM에 포함됨
- 3단계: 브라우저 렌더링 — 피해자 브라우저가 해당 HTML을 파싱하며 스크립트를 인식함
- 4단계: 스크립트 실행 — `document.cookie` 전송, 키로깅, 피싱 페이지 삽입 등 악성 행위 수행

> 요약: 삽입-반영-렌더링-실행의 4단계로 사용자 브라우저가 공격 실행 환경이 됨

## Ⅳ. 문제점
- 세션 탈취: 쿠키 접근으로 인증 세션이 도용되어 계정 장악이 가능함
- 피싱 확산: 신뢰 도메인 내 페이지 변조로 사용자가 위조 폼에 정보를 입력함
- 탐지 곤란: DOM-based XSS는 서버 로그에 흔적이 남지 않아 WAF만으로 차단 곤란함

> 요약: 세션 탈취, 피싱, 탐지 사각지대가 XSS의 핵심 위협임

## Ⅴ. 개선방안
1. 단기: 출력 시 HTML 엔티티 이스케이프 및 CSP 헤더 적용으로 인라인 스크립트 차단
2. 중기: 프레임워크 수준 자동 이스케이프(React JSX, Django autoescape) 적용 표준화
3. 장기: DOM Sanitizer API 도입 및 Trusted Types 정책으로 클라이언트측 주입 원천 차단

> 요약: 출력 이스케이프, 프레임워크 자동화, Trusted Types로 XSS를 계층적으로 방어함

## Ⅵ. 전망
- 발전 방향: SPA 확산으로 DOM-based XSS 비중이 증가하며 클라이언트측 보안의 중요성이 확대됨
- 기술사적 판단: CSP Level 3, Trusted Types 등 브라우저 네이티브 방어가 표준화될 전망
- 기술사 제언: 서버측 이스케이프와 브라우저 정책을 이중으로 적용하는 방어 설계가 필요함
