## 미리 알고가기

- SIEM은 탐지와 분석의 중심이고 SOAR는 대응 자동화의 중심임
- 둘은 대체 관계가 아니라 탐지 결과를 대응으로 연결하는 보완 관계임
- SIEM 없이 SOAR만 도입하면 입력 품질이 약하고 SOAR 없이 SIEM만 도입하면 대응 속도가 느려질 수 있음

## Ⅰ. 개요

- **정의/개념**: SIEM은 보안 로그와 이벤트를 통합 분석해 경보와 포렌식 기반을 제공하는 플랫폼이고, SOAR는 그 경보를 바탕으로 조사와 조치를 플레이북으로 자동화하는 대응 플랫폼임
- **배경/필요성**: 보안 운영은 탐지와 대응이 분리되면 병목이 생기므로 사건을 발견하는 체계와 사건을 빠르게 처리하는 체계를 함께 설계할 필요가 있음

## Ⅱ. 특징

- SIEM은 데이터 수집과 정규화와 상관분석에 강하고 SOAR는 반복 대응과 오케스트레이션에 강함
- SIEM은 포렌식과 감사 대응에도 쓰이지만 SOAR는 실행과 기록 자동화에 더 적합함
- SIEM 경보 품질이 높을수록 SOAR 플레이북 효과가 커짐
- 역할 경계를 구분하지 않으면 한 제품에 과도한 기대를 걸어 실패하기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | SIEM | SOAR |
|:---|:---|:---|
| 핵심 역할 | 로그 통합과 상관분석 | 조사·대응 자동화 |
| 입력 데이터 | 방대한 로그와 이벤트 | 경보와 케이스와 외부 API |
| 주요 산출물 | 경보, 검색, 포렌식 결과 | 차단, 격리, 티켓, 승인 이력 |
| 대표 한계 | 대응 속도는 사람 의존 | 입력 경보 품질에 의존 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SIEM Analytics | 로그 수집과 정규화와 상관분석으로 사건 후보를 만드는 탐지 계층임 |
| Alert Handoff | 경보와 문맥 정보를 SOAR로 넘겨 자동화 입력으로 바꾸는 연결 계층임 |
| SOAR Playbook | enrichment, 승인, 차단, 통보 같은 대응 절차를 자동 수행하는 실행 계층임 |
| Shared Case and Metrics | 두 플랫폼의 결과를 사건 단위와 운영 지표로 묶는 관리 계층임 |

```text
+-----------+    +----------------+    +----------------+    +----------------+
| Logs      | -> | SIEM Analytics | -> | SOAR Playbook  | -> | Action/Case    |
+-----------+    +----------------+    +----------------+    +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 로그 수집      | -> | SIEM 경보 생성 | -> | SOAR 보강/판단 | -> | 조치 실행      | -> | 결과 환류      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **로그 수집**: SIEM이 여러 보안 이벤트를 수집함
2. **SIEM 경보 생성**: 상관분석과 규칙으로 사건 후보를 만듦
3. **SOAR 보강과 판단**: 자산·CTI·사용자 정보를 보강하고 정책을 평가함
4. **조치 실행**: 계정 잠금, 단말 격리, 티켓 생성 같은 대응을 수행함
5. **결과 환류**: 조치 결과를 케이스와 탐지 튜닝에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 규제 산업의 중앙 관제는 SIEM으로 탐지 기반을 먼저 마련하고 SOAR로 반복 조치를 자동화하는 조합이 적합하지만 use case 없이 동시에 도입하면 복잡도만 커지므로 우선 탐지 시나리오를 정하고 경보당 대응 시간과 자동화 성공률과 오조치율로 확인함
2. 중소 조직은 SOAR에 기대를 크게 걸기 쉽지만 SIEM 경보 정합성이 낮으면 자동화 가치가 떨어지므로 핵심 로그와 고신뢰 경보부터 연결하고 자동화 적용 경보 비중과 재처리율로 확인함

## Ⅶ. 결론

- SIEM과 SOAR는 경쟁 기술이 아니라 탐지와 대응을 잇는 연속 체계이므로 경보 품질을 높인 뒤 자동화를 단계적으로 얹는 방식이 가장 현실적임
