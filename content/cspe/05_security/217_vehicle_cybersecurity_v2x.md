# 📖 【암기용】 개념 완전 이해

> 목적: 차량 사이버 보안과 V2X 위협을 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 차량 ECU, CAN/Ethernet, V2X, OTA를 대상으로 하는 위협을 전 수명주기에서 관리하는 자동차 보안 체계
- **왜 필요한가**: 차량은 네트워크에 연결된 이동형 컴퓨터가 되었고, 공격 결과가 개인정보 유출을 넘어 제동·조향·충돌 위험으로 연결된다. 양산 차량은 개발·생산·운영·폐차까지 10년 이상 관리가 필요하다.
- **핵심 직관**: 자동차 보안은 차 안의 작은 네트워크와 도로 위 차량 간 메시지를 모두 믿을 수 있게 만드는 일이다.

## 깊이 이해
- **배경·문제의식**: 차량은 텔레매틱스, 스마트키, Bluetooth, Wi-Fi, V2X, OTA, 진단 포트가 연결되며 외부 공격면이 늘었다. CAN은 메시지 인증이 약하고, ECU 권한 분리가 부족하면 한 지점 침해가 제동·조향 도메인으로 번진다.
- **작동 원리**: ISO/SAE 21434:2021은 road vehicles cybersecurity risk management lifecycle 표준으로 Item, TARA, Cybersecurity Goal, Concept, 검증, 운영 모니터링을 요구한다. UNECE R155는 CSMS, R156은 software update/SUMS를 요구하며 V2X는 PKI·오동작 탐지·폐기·OTA 보안이 함께 필요함.
- **비유**: 차량은 아파트 단지와 같다. 정문(텔레매틱스), 주차장(V2X), 관리실(OTA), 세대 내부(CAN)가 연결되어 있어 한 출입구만 통제해도 전체 위험을 막을 수 없다.
- **구체 예시**: V2X Basic Safety Message 위조로 앞 차량 급제동 경고가 발생할 수 있다. 대응은 IEEE 1609.2 인증서 검증, pseudonym certificate, misbehavior report, CRL 배포임.
- **흔한 오해·주의점**: 차량 보안은 암호화만으로 끝나지 않는다. 실시간성, 인증서 프라이버시, OTA 롤백, ECU 리소스, 기능 안전과 충돌하지 않는 통제가 필요하다.

## 연결 개념
- ISO/SAE 21434 - 차량 사이버보안 수명주기
- UNECE R155/R156 - CSMS와 SUMS 규제 축
- Vehicle PKI - V2X 메시지 인증·프라이버시 기반

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 수치·표준·도식·문제유형 전환을 엄격히 적용한다.
> 핵심: 차량 보안은 ECU 보호만이 아니라 V2X 메시지 신뢰, OTA 갱신, CAN/Ethernet 분리, CSMS 운영을 연결해 답해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 차량 사이버 보안은 차량 E/E 아키텍처와 V2X 통신의 위협을 ISO/SAE 21434 수명주기로 식별·평가·통제하는 체계이다.
> 2. **가치**: 인증된 V2X 메시지, 안전한 OTA, 게이트웨이 분리, IDS로 오동작·원격 장악·개인정보 노출 위험을 낮춘다.
> 3. **판단 포인트**: ISO/SAE 21434, UNECE R155 CSMS, R156 SUMS, IEEE 1609.2/ETSI ITS PKI를 각각 역할별로 구분해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 차량 보안 표준·규제 이해 확인 | ISO/SAE 21434:2021, UNECE R155 CSMS, R156 SUMS | 표준명을 나열하고 수명주기 역할 누락 |
| V2X 특화 위협 판단 확인 | PKI, pseudonym certificate, misbehavior detection, CRL | 일반 무선 보안으로만 설명 |
| 차량 내부 공격면 통제 확인 | CAN/Ethernet, ECU, TCU, OTA, 진단 포트 | 외부 통신만 쓰고 차량 내부 전파 누락 |

> 요약: 이 문제는 차량 외부 연결과 내부 제어망을 수명주기·규제·V2X 신뢰모델로 연결하는 답안을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 차량 통신·제어 수명주기 보안
- 배경: V2X 안전 메시지의 위조·재전송·오동작은 제동·조향 판단에 영향을 주고, 양산 차량은 개발 이후 10년 이상 운행됨
- 필요성: ISO/SAE 21434, UNECE R155 CSMS, R156 SUMS, IEEE 1609.2 기준으로 TARA·OTA·V2X 인증을 전 수명주기에 적용해야 함

---

## Ⅱ. 구조 및 구성요소

```text
External Network -> TCU/V2X OBU -> Security Gateway -> Domain ECU
                                      +-> CAN/Ethernet -> Sensor/Actuator
OTA Backend -> SUMS -> Signed Package -> Vehicle Update -> Monitoring
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| TCU/V2X OBU | LTE/5G, V2X, 클라우드 접점 | 외부 공격면, 인증서 검증 필요 |
| Security Gateway | 도메인 간 메시지 필터링 | CAN ID 허용목록, Ethernet ACL 적용 |
| ECU/CAN/Ethernet | 제어 기능 실행, 내부 통신 | 메시지 인증·분리·IDS 필요 |
| OTA/SUMS | 소프트웨어 갱신 배포·검증 | 서명 검증, 롤백, 설치 로그 필요 |

> 요약: 차량 보안 구조는 외부 통신 접점, 내부 제어망, OTA 운영망을 보안 게이트웨이와 인증 체계로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Item 식별 -> TARA 수행 -> Cybersecurity Goal 수립
-> 보안 요구사항 설계 -> 구현·검증 -> 생산·운영 모니터링
-> OTA 패치·인증서 폐기 -> 사고 피드백
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Item과 자산 식별, 공격 경로 도출 | TCU·V2X·CAN·OTA 포함 |
| 2 | TARA로 영향도·공격 가능성 평가 | Cybersecurity Goal 추적성 |
| 3 | Gateway 필터, V2X PKI, OTA 서명 설계 | ISO/SAE 21434 요구사항 매핑 |
| 4 | 침투시험, Fuzzing, HIL 검증 수행 | 고위험 취약점 0건 출고 |
| 5 | CSMS 운영, OTA 패치, 오동작 탐지 | R155/R156 감사 증적 |

> 요약: 차량 보안은 TARA에서 시작해 양산 후 모니터링·OTA·폐기까지 이어지는 폐루프 관리이다.

## Ⅳ. 특징

| 구분 | 일반 IoT 보안 | 차량 V2X 보안 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 수명주기 | 제품 출시 후 패치 중심 | 개발·양산·운영·폐차 전 단계 | ISO/SAE 21434:2021 |
| 통신 신뢰 | TLS·API 인증 | IEEE 1609.2/ETSI ITS 인증서 | pseudonym certificate |
| 규제 | 권고·인증 중심 | 형식승인과 사후관리 | UNECE R155/R156 |
| 위험 영향 | 데이터 유출·서비스 장애 | 제동·조향·충돌 위험 | ASIL·TARA 연계 |

> 요약: 차량 V2X 보안은 통신 암호보다 메시지 신뢰, 안전 영향, 규제 증적을 함께 판단해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 차량 V2X 보안 | 선택 기준 |
|:---|:---|:---|:---|
| 위협분석 | STRIDE 중심 | TARA 기반 위협·위험 평가 | 안전 영향과 공격 가능성 동시 평가 |
| 통신보호 | TLS 세션 보호 | V2X 메시지 서명·인증서 폐기 | 브로드캐스트 안전 메시지 필요 시 |
| 갱신운영 | 서비스 패치 | SUMS 기반 OTA 서명·롤백 | 형식승인 변경 관리 필요 시 |

> 요약: 차량 보안은 일반 IT 보안보다 규제 증적, 안전 영향, 장기 운행 관점의 선택 기준이 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| V2X 메시지 위조 | 인증서 탈취, 재전송 | IEEE 1609.2 서명, nonce, timestamp | 위조 메시지 수락률 0% |
| 내부망 전파 | TCU 침해 후 CAN 접근 | Security Gateway, CAN ID 필터 | 미승인 CAN frame 0건 |
| OTA 공급망 침해 | 패키지 서명키 유출 | HSM, 이중서명, 롤백 방지 | 서명 검증 실패 차단 100% |

> 요약: 주요 리스크는 V2X 신뢰 붕괴, 내부 제어망 전파, OTA 공급망 침해이며 각각 인증·분리·서명으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| TARA 추적성 | 고위험 항목 요구사항 매핑 100% | ALM, 요구사항 관리도구 |
| V2X 신뢰 | 인증서 검증 실패 메시지 차단 100% | OBU 로그, 현장 주행시험 |
| 운영대응 | CVE 평가 72시간 이내, OTA 배포 승인 기록 | CSMS/SUMS 감사로그 |

> 요약: 도입 효과는 TARA 추적성, V2X 메시지 검증률, 운영 대응 시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ISO/SAE 21434 기반 Item-TARA-Cybersecurity Goal 추적성 구축, 고위험 자산 100% 요구사항 매핑
2. V2X OBU에 IEEE 1609.2/ETSI ITS 인증서 검증, pseudonym certificate 교체, misbehavior report 절차 적용
3. UNECE R155 CSMS와 R156 SUMS에 맞춰 OTA 서명·롤백·배포 로그를 HSM과 감사 저장소로 관리

**결론 (2줄):**
- 기술사 판단: V2X 기능 차량이면 PKI·오동작 탐지·OTA 운영을 우선 설계하고, 비연결 차량이면 게이트웨이와 진단 포트 통제를 우선 적용함
- 향후 방향: SDV 전환으로 차량 보안은 ECU 단위 통제에서 클라우드-차량-도로 인프라 통합 운영으로 확대됨
