## 미리 알고가기

- 네임스페이스는 프로세스가 보는 PID, 네트워크, 파일시스템 같은 시스템 자원을 분리하는 리눅스 격리 기능임
- cgroup은 CPU, 메모리, I/O 같은 자원 사용량을 제한하고 계측하는 기능임
- 컨테이너는 가상머신처럼 커널을 따로 두지 않고 네임스페이스와 cgroup으로 분리 효과를 만듦

## Ⅰ. 개요

- **정의/개념**: 네임스페이스와 cgroup은 컨테이너가 서로의 프로세스와 네트워크를 보지 못하게 나누고 각자가 쓸 수 있는 자원 양도 제한하는 리눅스 핵심 격리 구조임
- **배경/필요성**: 여러 애플리케이션이 한 호스트를 함께 쓸 때 가시성 분리와 자원 제한이 없으면 한 서비스의 침해나 폭주가 곧바로 다른 서비스 장애와 정보 노출로 이어짐

## Ⅱ. 특징

- 네임스페이스는 보이는 세계를 나누고 cgroup은 쓸 수 있는 자원 양을 나눔
- 커널 공유 구조라 가상머신보다 가볍고 시작 속도가 빠름
- 컨테이너 보안의 출발점이지만 이것만으로 완전한 보안이 되지는 않음
- 권한 상승과 특권 컨테이너를 허용하면 격리 효과가 크게 약해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 네임스페이스 | cgroup |
|:---|:---|:---|
| 주된 역할 | 프로세스, 네트워크, 마운트 공간을 분리함 | CPU, 메모리, I/O 사용량을 제한함 |
| 보는 문제 | 서로를 보거나 간섭하는 문제 | 한 워크로드가 자원을 독식하는 문제 |
| 대표 자원 | PID, NET, MNT, IPC, UTS, USER | CPU quota, memory limit, blkio |
| 부족한 점 | 자원 폭주 자체는 직접 못 막음 | 정보 가시성 분리는 직접 못 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| PID 네임스페이스 | 컨테이너마다 프로세스 목록을 분리해 다른 프로세스를 보지 못하게 함 |
| NET 네임스페이스 | 네트워크 인터페이스와 라우팅 공간을 분리함 |
| MNT 네임스페이스 | 마운트 지점을 분리해 파일시스템 가시 범위를 좁힘 |
| USER 네임스페이스 | 컨테이너 내부 사용자 ID와 호스트 사용자 ID를 다르게 매핑함 |
| cgroup 제어 | CPU, 메모리, I/O 한도를 걸고 사용량을 계측함 |

```text
호스트 커널
  -> 네임스페이스로 가시성 분리
  -> cgroup으로 자원 한도 부여
  -> 컨테이너별 독립 실행
```

## Ⅴ. 원리 및 절차 흐름도

```text
컨테이너 생성 -> 네임스페이스 할당 -> cgroup 한도 설정 -> 프로세스 실행 -> 격리와 자원 제한 유지
```

1. **컨테이너 생성**: 런타임이 새 실행 공간을 준비함
2. **네임스페이스 할당**: 프로세스와 네트워크와 파일시스템 가시 범위를 분리함
3. **자원 한도 설정**: CPU와 메모리와 I/O 한도를 부여함
4. **프로세스 실행**: 애플리케이션이 분리된 공간에서 동작함
5. **상태 유지**: 커널이 격리와 자원 제한을 계속 적용함

## Ⅵ. 실무 적용 및 유의점

1. 여러 팀이 노드를 함께 쓰는 클러스터는 네임스페이스 격리와 자원 한도를 함께 걸어야 하며 노드 OOM 발생 건수와 과도한 CPU 점유로 인한 장애 건수로 확인함
2. 특권 컨테이너와 호스트 경로 마운트는 격리를 약하게 하므로 사용 범위를 최소화하고 특권 파드 수와 호스트 파일시스템 접근 탐지 건수로 점검함

## Ⅶ. 결론

- 네임스페이스와 cgroup은 컨테이너의 성능 기능이 아니라 보안과 안정성을 받치는 기본 격리 구조이므로 가시성 분리와 자원 통제를 항상 함께 설계해야 함
