## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 암호화할 때와 복호화할 때 **서로 다른 두 개의 키(Public Key, Private Key) 쌍**을 사용하는 암호화 방식입니다.
- **필요성**: 서로 만난 적 없는 두 사람이 안전하게 비밀키를 교환하거나(키 분배), 데이터의 출처를 증명(전자서명)하기 위해 필요합니다.
- **핵심 직관**: **"우편함 비유"**. 공개키는 누구나 투입할 수 있도록 뚫려있는 '우편함의 입구'입니다. 누구나 내 우편함에 편지를 넣을(암호화할) 수 있지만, 그 우편함을 열어 편지를 읽을(복호화할) 수 있는 사람은 '우편함 열쇠(개인키)'를 가진 나뿐입니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 1976년 Diffie와 Hellman이 '키 분배 문제'를 해결하기 위한 수학적 개념을 제시했고, 1977년 RSA가 이를 실용화했습니다. 이는 암호학 역사상 가장 위대한 혁명(Public-Key Revolution)으로 불립니다.
- **해결하는 문제**: $N$명이 통신할 때 $\frac{N(N-1)}{2}$개의 키가 필요한 대칭키의 한계를 극복하고, 단 $2N$개의 키만으로 전 세계적인 보안 통신망(인터넷)을 구축할 수 있게 만들었습니다.

## 3. 어떻게 작동하는가? (Mechanism)
- **작동 원리 (Step-by-Step)**:
  1. **Key Generation**: 수신자(Bob)가 공개키(Public Key)와 개인키(Private Key) 쌍을 생성합니다. 개인키는 절대 유출되지 않게 보관하고, 공개키는 세상에 공개합니다.
  2. **Encryption**: 송신자(Alice)는 인터넷에서 Bob의 공개키를 다운받아 메시지를 암호화합니다.
  3. **Transmission**: 암호문을 Bob에게 보냅니다. (이 암호문은 Bob의 공개키로도 풀 수 없습니다).
  4. **Decryption**: Bob은 자신의 개인키로 암호문을 복호화하여 원본 메시지를 확인합니다.

- **수학적 난제 (Trapdoor One-way Function)**:
  - 한 방향(암호화)으로는 계산이 매우 쉽지만, 역방향(복호화)으로는 특정한 '비밀 정보(Trapdoor=개인키)' 없이는 계산이 천문학적으로 어려운 수학적 함수에 기반합니다.
  - 예: 소인수분해 문제 (RSA), 이산대수 문제 (DH, DSA), 타원곡선 이산대수 문제 (ECC).

```ascii
[Alice]                                   [Bob]
                                          1. Key Generation
                                             ├─ Public Key (공개)
                                             └─ Private Key (보관)
 평문 (P) 
   │
   ▼
┌───────┐
│ 암호화 │<─── [Bob의 Public Key] ────────── (인증서 등을 통해 공개)
└───────┘
   │
   ▼                                          
 암호문 (C) ─────────────────────────────▶ 암호문 (C)
                                              │
                                              ▼
                                           ┌───────┐
                                           │ 복호화 │<── [Bob의 Private Key]
                                           └───────┘
                                              │
                                              ▼
                                            평문 (P)
```

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례**: 
  - **웹 브라우징 (HTTPS)**: 서버의 인증서에 포함된 RSA/ECC 공개키를 이용해 클라이언트가 대칭키(세션키)를 암호화하여 서버로 전달합니다 (Key Transport).
  - **공동인증서 (구 공인인증서)**: 송신자가 자신의 **개인키**로 암호화(서명)하면, 수신자가 송신자의 **공개키**로 복호화(검증)하여 신원을 확인하고 부인방지를 수행합니다.
- **주의점 및 흔한 오해**: 
  - 공개키 암호는 **매우 느립니다**(대칭키 대비 약 1000배). 따라서 긴 메시지를 직접 공개키로 암호화하지 않으며, 짧은 대칭키나 해시값을 암호화하는 데만 사용합니다.
  - "공개키가 진짜 그 사람의 것인가?"를 보증하는 제3자(CA) 시스템인 PKI(Public Key Infrastructure)가 필수적입니다.

## 5. 핵심 비교 및 연결 개념 (Relation)
- **VS 대칭키 암호**: 대칭키는 기밀성+고속, 비대칭키는 키 분배+전자서명+느림.
- **연결 개념**: 
  - **RSA**: 가장 널리 쓰이는 소인수분해 기반 공개키 알고리즘.
  - **ECC (타원곡선 암호)**: RSA보다 훨씬 짧은 키 길이로 동급의 보안을 제공하여 모바일/IoT 환경의 표준이 됨.

# ✍️ 【답안용】 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 암호화(Public Key)와 복호화(Private Key) 키를 분리하여 트랩도어 일방향 함수(Trapdoor One-way Function)를 구현한 암호 시스템.
- **가치**: O(N²)의 키 관리 복잡도를 O(N)으로 줄이고, 디지털 환경에서 서명 및 부인방지(Non-repudiation)를 가능케 한 현대 인터넷 보안의 근간.
- **판단 포인트**: 연산 부하가 매우 크므로 대용량 데이터 암호화에는 부적합하며, 대칭키 분배(Key Exchange) 및 전자서명(Digital Signature) 목적으로 제한적/결합적(Hybrid)으로 사용해야 함.

### Ⅱ. 비대칭키 암호의 개념 및 수학적 기반
**1. 개념**
- 한 쌍의 키를 생성하여, 공개키는 누구나 접근 가능한 디렉토리에 공개하고 개인키는 소유자만이 안전하게 보관하는 구조. 
- **기밀성 모드**: `수신자의 공개키`로 암호화 $\rightarrow$ `수신자의 개인키`로 복호화 (안전한 메시지 전달)
- **인증/서명 모드**: `송신자의 개인키`로 암호화 $\rightarrow$ `송신자의 공개키`로 복호화 (출처 증명 및 부인방지)

**2. 수학적 난제 (Mathematical Hard Problems)**
- **소인수분해 문제 (Factoring Problem)**: 두 개의 큰 소수 $p, q$를 곱하여 $n=pq$를 구하기는 쉽지만, $n$에서 $p, q$를 유도하기는 극히 어렵다는 성질. (RSA)
- **이산대수 문제 (Discrete Logarithm Problem, DLP)**: $y = g^x \pmod p$ 에서 $g, x, p$를 알면 $y$를 구하기 쉽지만, $y, g, p$가 주어졌을 때 $x$를 구하는 것은 어렵다는 성질. (ElGamal, Diffie-Hellman)
- **타원곡선 이산대수 문제 (ECDLP)**: 타원곡선 상의 점 덧셈 연산에서, $Q = kP$를 만족하는 스칼라 $k$를 찾는 것이 어렵다는 성질. (ECC, ECDSA)

### Ⅲ. 주요 비대칭키 알고리즘 비교
| 특성 | RSA | ECC (Elliptic Curve Cryptography) | ElGamal |
|---|---|---|---|
| **수학적 난제** | 큰 수의 소인수분해 | 타원곡선 이산대수 (ECDLP) | 이산대수 (DLP) |
| **안전성 (키 길이)** | 2048~4096 bit 필요 | **256 bit** (RSA 3072bit와 동급) | 2048 bit 이상 필요 |
| **장점** | 구현이 쉽고 사실상 업계 표준 | 키 길이가 짧아 연산/메모리 효율 극대화 | 암호문 크기가 평문의 2배가 되나, 난수 사용 |
| **주요 용도** | 키 교환, 전자서명 (TLS, 공동인증서) | 모바일, IoT, 블록체인 서명 (ECDSA) | 암호화, 전자서명 |

### Ⅳ. 비대칭키 암호의 주요 활용 모델
1. **전자서명 (Digital Signature)**
   - 평문의 해시(Hash)값을 구한 뒤, 이를 송신자의 개인키로 암호화하여 평문과 함께 전송. 무결성과 부인방지 달성.
2. **키 교환 및 캡슐화 (Key Exchange / KEM)**
   - 대칭키(세션키)를 생성한 후, 이를 수신자의 공개키로 암호화하여 전달함으로써 안전한 대칭키 채널 형성 (TLS Handshake의 핵심).
3. **PKI (Public Key Infrastructure)**
   - 신뢰할 수 있는 제3자(CA; Certificate Authority)가 사용자의 공개키를 전자서명하여 X.509 인증서 형태로 발급. 중간자 공격(MITM) 방지.

### Ⅴ. 양자 컴퓨터 위협과 Post-Quantum 대응 방안
- **Shor's Algorithm 위협**: 양자 컴퓨터가 상용화되면 Shor 알고리즘에 의해 소인수분해(RSA) 및 이산대수(ECC) 기반 암호가 다항 시간 내에 파훼됨.
- **PQC (Post-Quantum Cryptography) 전환**: NIST의 PQC 표준화 완료(2024.08)에 따라, FIPS 203 (ML-KEM, 구 Kyber) 및 FIPS 204 (ML-DSA, 구 Dilithium) 기반 격자(Lattice) 암호 체계로의 마이그레이션 전략이 필수적임.

### Ⅵ. 결론 및 실무적 판단 포인트
- **암호화 성능 최적화**: 웹 서버 트래픽 폭증 시 RSA 연산이 CPU 병목을 유발하므로, RSA 대신 ECC(ECDHE, ECDSA)를 우선 적용하여 서버 부하를 줄이고 세션 성립 속도를 높여야 함.
- **키 생명주기 관리**: 개인키 유출 시 시스템 전체의 신뢰가 붕괴되므로, 개인키는 반드시 HSM(Hardware Security Module)이나 TEE(Trusted Execution Environment) 내부에서만 생성 및 사용되도록 통제해야 함.

### 💡 문제 유형별 목차 전환 포인트
- **[RSA 상세 원리 묻는 유형]**: Ⅱ. 개념을 RSA 키 생성 절차($p, q \rightarrow n, \phi(n) \rightarrow e, d$), 암호화($C = P^e \bmod n$), 복호화($P = C^d \bmod n$) 수식으로 대체하여 상세 전개.
- **[미래 위협 및 대응]**: Ⅴ번 항목을 메인으로 끌어올려 양자 내성 암호(PQC) 마이그레이션(하이브리드 모드 등)을 중점적으로 서술.
