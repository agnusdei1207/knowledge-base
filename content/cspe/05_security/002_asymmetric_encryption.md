# 📖 【암기용】 개념 완전 이해

> 목적: 비대칭 암호화를 처음 보는 사람도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 공개키와 개인키 한 쌍으로 암호화·복호화 또는 서명을 수행하는 암호 방식
- **왜 필요한가**: 인터넷에서는 사전에 비밀키를 공유하기 어렵다. 공개키 암호는 공개키를 누구에게나 배포하고 개인키만 보호해 키 분배 문제를 줄인다.
- **핵심 직관**: 우편함 투입구는 모두에게 공개하지만, 우편함을 여는 열쇠는 소유자만 가진 구조임

## 깊이 이해
- **배경·문제의식**: 대칭 암호는 양쪽이 같은 키를 미리 가져야 한다. RSA·ECC는 수학적으로 연결된 키 쌍을 사용해, 공개 네트워크에서도 세션키 전달과 전자서명 검증을 가능하게 함.
- **작동 원리**: RSA는 큰 정수 소인수분해 난이도, ECC는 타원곡선 이산로그 난이도에 기반한다. 암호화는 수신자 공개키로 수행하고 복호화는 수신자 개인키로 수행함.
- **비유**: 누구나 넣을 수 있는 잠금 우편함과 같다. 투입구 위치는 공개되어도 우편함 문을 여는 열쇠는 개인키 보유자만 가진다.
- **구체 예시**: TLS 1.2는 RSA 키 교환을 사용했지만 TLS 1.3은 RSA 키 교환을 제거하고 ECDHE로 전방향 안전성을 제공함. 인증서는 RSA-2048 또는 ECDSA P-256을 사용함.
- **흔한 오해·주의점**: 공개키 암호는 본문 전체를 암호화하는 수단이 아니다. 처리 비용과 입력 크기 제한 때문에 세션키 교환·서명·키 캡슐화에 사용하고, 본문은 AES-GCM으로 암호화함.

## 연결 개념
- PKI — 공개키의 소유자 신뢰를 인증서로 보증
- 전자서명 — 개인키로 서명하고 공개키로 검증
- 하이브리드 암호 — 비대칭 암호로 대칭 세션키를 안전하게 전달

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 비대칭 암호화는 공개키와 개인키를 분리해 키 분배, 인증, 전자서명 문제를 해결하는 암호 체계이다.
> 2. **가치**: RSA·ECC는 TLS, PKI, 코드서명, 전자문서에서 신원 확인과 세션키 보호를 담당함.
> 3. **판단 포인트**: 본문 암호화가 아니라 키 교환·서명·인증에 배치하고, 키 길이와 인증서 수명·폐지 상태를 함께 관리해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공개망 위장·중간자·부인 위협을 PKI 통제, 인증서 검증, 개인키 보호, 폐지 확인과 연결하는 역량 확인 | 공개키/개인키 역할, RSA-2048·ECC P-256, X.509, CA chain, CRL/OCSP, HSM, 전자서명의 무결성·인증·부인방지 | 공개키로 본문 전체 암호화 가정, 인증서 폐지 누락, 암호화와 서명 목적 혼동 |

> 요약: 비대칭 암호 답안은 키 쌍 구조보다 인증서 신뢰와 개인키 통제까지 확장해야 한다.

## Ⅰ. 개요 및 필요성

비대칭 암호는 공개키와 개인키를 분리한 암호이다. 공개 네트워크에서는 사전 비밀키 공유가 어렵기 때문에 공개키 기반 키 교환과 전자서명이 필요하다. RSA-2048, ECC P-256, ECDHE는 웹·클라우드·전자서명 신뢰 체계의 기본 요소임.

---

## Ⅱ. 구조 및 구성요소

```text
Key Pair Generation -> Public Key Distribution -> Certificate Binding
Private Key -> Decryption/Signing
Public Key -> Encryption/Verification
PKI -> CA -> CRL/OCSP -> Trust Validation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 공개키 | 암호화·서명 검증 | 인증서로 소유자 바인딩 필요 |
| 개인키 | 복호화·서명 생성 | HSM·TPM·파일 권한으로 보호 |
| 알고리즘 | RSA·ECC·ECDHE | RSA-2048 이상, P-256 이상 권장 |
| 인증서 | 공개키 신뢰 증명 | X.509, CA 서명, CRL/OCSP 폐지 확인 |

> 요약: 비대칭 암호는 키 쌍, 알고리즘, 인증서, 폐지 검증이 함께 동작할 때 신뢰 가능한 공개키 사용이 가능하다.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 쌍 생성 -> 공개키 인증서 발급 -> 상대방 인증서 검증
-> 공개키로 세션키 보호 또는 서명 검증 -> 개인키로 복호화 또는 서명
-> CRL/OCSP로 폐지 상태 확인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | RSA/ECC 키 쌍 생성 | RSA-2048 이상, ECDSA P-256 이상 |
| 2 | CA가 X.509 인증서 발급 | Subject, SAN, KeyUsage 확인 |
| 3 | 공개키로 암호화 또는 서명 검증 | 인증서 체인·만료·폐지 검증 |
| 4 | 개인키로 복호화 또는 서명 생성 | 개인키 접근 로그·HSM 정책 |

> 요약: 비대칭 암호는 키 생성, 인증서 신뢰 확인, 공개키 처리, 개인키 보호 순서로 동작한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 사전 비밀키 공유 없이 신뢰 연결 | PKI·CA·OCSP 기반 신원 검증 |
| 한계 | 대량 본문 암호화에는 연산 비용 큼 | RSA는 입력 크기 제한, ECC는 구현 검증 필요 |
| 비교 대상 | RSA·ECC | RSA-2048과 ECC P-256은 유사 보안 수준, ECC 키 길이 짧음 |

> 요약: 비대칭 암호는 키 분배와 인증에 적합하고, 대량 데이터는 대칭 암호와 결합해 처리한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 사전 공유키 | 공개키·개인키 쌍 | 불특정 다수 통신, 외부 사용자 인증 |
| 비용/성능 | AES 본문 암호화 | RSA/ECC 키 교환·서명 | 본문은 AES, 키와 인증은 RSA/ECC |
| 운영/위험 | 자체 키 배포 | PKI·인증서 체인 | CA 신뢰, 폐지, 만료 관리 필요 |

> 요약: 공개망 인증과 키 교환은 비대칭 암호를 선택하고, 데이터 본문은 대칭 암호로 분리한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 개인키 유출 | 파일 저장·권한 과다 | HSM/TPM, 키 내보내기 금지 | 개인키 export 0건 |
| 인증서 오용 | CN/SAN 불일치·만료 | 자동 갱신, OCSP Stapling | 만료 30일 전 알림 100% |
| 알고리즘 노후 | RSA-1024·SHA-1 사용 | RSA-2048 이상, SHA-256 이상 | 약한 인증서 0건 |

> 요약: 비대칭 암호 리스크는 개인키 보호, 인증서 수명, 알고리즘 수명주기 관리로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 키 강도 | RSA-2048 이상, ECC P-256 이상 | 인증서 스캔 |
| 인증서 상태 | 만료·폐지·체인 오류 0건 | CRL/OCSP, TLS 진단 |
| 개인키 통제 | HSM 저장, 접근 감사 100% | HSM 로그·IAM 정책 |

> 요약: 적용 품질은 키 길이, 인증서 상태, 개인키 접근통제로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. TLS 서버 인증서: RSA-2048 이상 또는 ECDSA P-256 인증서 사용, SAN 검증과 OCSP Stapling 적용
2. 개인키 보호: HSM·TPM에 개인키 저장, 관리자 2인 승인, 키 내보내기 차단 정책 적용
3. 알고리즘 관리: SHA-1·RSA-1024 인증서 차단, 398일 이하 인증서 수명과 자동 갱신 파이프라인 운영

**결론 (2줄):**
- 기술사 판단: 비대칭 암호는 공개망 신뢰와 키 교환에 배치하고, 본문 암호화는 AES-GCM과 결합해야 함
- 향후 방향: 양자컴퓨팅 리스크에 대비해 RSA/ECC 의존 구간을 식별하고 ML-KEM·ML-DSA 전환 계획 수립 필요
