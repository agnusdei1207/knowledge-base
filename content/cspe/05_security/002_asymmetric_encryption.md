## 미리 알고가기

- 공개키: 누구나 사용할 수 있도록 배포되는 키임
- 개인키: 소유자만 보관하며 복호화나 서명 생성에 쓰는 키임
- Trapdoor 함수: 공개 정보로 계산은 쉽지만 비밀 정보 없이는 역산이 어려운 함수임
- 키 교환: 통신 양측이 같은 세션키 재료를 합의하는 절차임
- 전자서명: 개인키로 서명하고 공개키로 검증하는 출처 확인 방식임

## Ⅰ. 개요

- **정의/개념**: 비대칭 암호화는 서로 다른 공개키와 개인키 쌍으로 암호화·복호화 또는 서명·검증을 수행하는 방식임
- **배경/필요성**: 사전 비밀키 공유가 어려운 인터넷 환경에서는 키 분배와 신원 검증을 공개키 기반으로 처리할 필요가 있음

## Ⅱ. 특징

- 공개키는 배포 가능하지만 개인키는 유출되면 신뢰 경계가 무너짐
- 대용량 데이터 암호화보다 세션키 합의와 서명 검증에 주로 사용됨
- 공개키가 소유자에게 속한다는 사실은 인증서와 PKI로 검증함
- RSA·ECC 계열은 양자 공격에 대비한 PQC 전환 대상임

## Ⅲ. 종류 및 비교

| 구분 | RSA | ECC |
|:---|:---|:---|
| 기반 난제 | 큰 정수 소인수분해 | 타원곡선 이산대수 |
| 키 크기 | 같은 보안 강도에서 상대적으로 큼 | 같은 보안 강도에서 상대적으로 작음 |
| 활용 | 암호화, 서명, 레거시 PKI | ECDHE, ECDSA, 모바일·IoT |
| 양자 영향 | 쇼어 알고리즘 영향 대상 | 쇼어 알고리즘 영향 대상 |
| 적용 판단 | 기존 시스템 호환성 | 키·서명 크기와 연산 비용 절감 |

> 요약: RSA와 ECC는 기반 난제가 다르지만 공개키 신뢰와 개인키 보호가 공통 운영 조건임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 공개키 | 암호화 또는 서명 검증에 사용 |
| 개인키 | 복호화 또는 서명 생성에 사용 |
| 인증서 | 공개키와 주체 식별 정보를 결합 |
| CA | 인증서 서명으로 공개키 소유자를 보증 |
| 폐지 정보 | 유출·오발급 인증서를 신뢰 경로에서 제외 |

```text
송신자 -- 수신자 공개키로 암호화 --> 암호문 -- 수신자 개인키로 복호화 --> 평문

서명자 -- 개인키로 서명 --> 서명값 -- 공개키로 검증 --> 출처·무결성 확인
```

## Ⅴ. 원리 및 절차 흐름도

```text
키쌍 생성 -> 공개키 배포 -> 인증서 검증 -> 암호화/서명 -> 복호화/검증 -> 폐지 확인
```

1. **키쌍 생성**: 공개 가능한 값과 비밀 값을 수학적으로 연결해 생성함
2. **공개키 배포**: 인증서나 키 디렉터리를 통해 상대방에게 전달함
3. **신뢰 검증**: CA 서명과 인증서 체인을 확인함
4. **암호 처리**: 목적에 따라 공개키 암호화 또는 개인키 서명을 수행함
5. **운영 관리**: 개인키 보관, 인증서 갱신, 폐지 상태를 관리함

## Ⅵ. 실무 적용 및 유의점

- TLS에서는 공개키 암호만으로 데이터를 암호화하지 않고 세션키 합의에 사용함
- 개인키는 HSM, KMS, 접근 통제로 생성·보관·사용 경로를 제한함
- 인증서 검증 없이 공개키만 쓰면 중간자 공격을 막을 수 없음
- 장기 인증서와 코드 서명은 PQC 전환 영향을 먼저 받음
- 알고리즘 선택은 호환성, 키 크기, 서명 크기, 전환 일정으로 판단함

## Ⅶ. 결론

- 비대칭 암호화의 주된 역할은 공개 환경에서 키 분배와 신원 검증을 가능하게 하는 것임
- 답안의 판단 기준은 연산 속도가 아니라 공개키 신뢰, 개인키 보호, 인증서 검증 절차임

## 작성 근거(검토용)

- 비대칭 암호를 “안전한 암호”로 뭉뚱그리지 않고 키 분배와 서명 역할로 분리함
- RSA·ECC 비교는 기술사 답안에서 필요한 난제, 키 크기, 적용 조건만 남김
- `보증`, `신뢰`는 CA·인증서 검증이라는 주체가 있을 때만 사용하도록 문맥을 제한함
