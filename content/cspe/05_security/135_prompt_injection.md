## 미리 알고가기

- 시스템 프롬프트는 서비스가 모델에 미리 주는 기본 지침임
- 검색 증강 생성은 외부 문서 검색 결과를 함께 넣어 답변하는 방식이며 보통 RAG라고 부름
- 도구 호출은 모델이 메일 전송, 데이터 조회, 파일 수정 같은 외부 기능을 실행하는 구조임

## Ⅰ. 개요

- **정의/개념**: 프롬프트 인젝션은 사용자 입력이나 외부 문서에 숨긴 지시로 모델의 원래 안전 지침과 역할 규칙을 흔들어 잘못된 응답이나 도구 실행을 유도하는 공격임
- **배경/필요성**: 대형 언어모델은 자연어 입력을 명령처럼 해석하므로 악성 문장이 데이터와 같은 경로로 들어오면 전통적인 입력 검증만으로는 공격 의도를 구분하기 어려움

## Ⅱ. 특징

- 코드 주입처럼 구문 오류가 드러나지 않아 일반 텍스트로도 공격이 성립함
- 사용자가 직접 넣은 문장뿐 아니라 웹페이지와 문서와 이메일에 숨겨진 지시도 위험함
- 모델 출력 오류에 그치지 않고 외부 도구 오남용과 정보 유출로 이어질 수 있음
- 금칙어 차단만으로는 우회가 쉬우므로 입력 분리와 권한 축소가 함께 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 프롬프트 인젝션 | 간접 프롬프트 인젝션 |
|:---|:---|:---|
| 공격 위치 | 사용자가 대화 입력에 직접 지시를 넣음 | 외부 문서, 웹페이지, 메일에 지시를 숨김 |
| 흔한 상황 | 챗봇 우회, 정책 무시 유도 | RAG, 브라우징, 메일 요약, 에이전트 서비스 |
| 방어 초점 | 시스템 지침 보호와 도구 권한 제한 | 신뢰하지 않는 외부 콘텐츠 분리와 정화 |
| 위험성 | 즉시 테스트가 쉬움 | 사용자가 모르는 사이에 실행될 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시스템 프롬프트 | 모델이 지켜야 할 역할과 금지 규칙을 정의함 |
| 사용자 입력 | 정상 질의와 공격 지시가 함께 들어오는 창구임 |
| 외부 콘텐츠 | 검색 결과, 문서, 메일처럼 신뢰하지 않는 입력 원천임 |
| 도구 권한 | 모델이 실제로 호출할 수 있는 외부 기능 범위를 정함 |
| 출력 검토 | 민감정보 유출과 위험한 도구 실행을 마지막에 거름 |

```text
시스템 지침 + 사용자 입력 + 외부 콘텐츠 -> 모델 해석 -> 응답 또는 도구 호출 -> 출력 검토
```

## Ⅴ. 원리 및 절차 흐름도

```text
입력 수집 -> 지시 충돌 발생 -> 모델이 공격 문장 수용 -> 민감정보 응답 또는 도구 실행 -> 차단 또는 기록
```

1. **입력 수집**: 사용자 문장과 외부 문서를 함께 읽음
2. **지시 충돌 발생**: 원래 지침과 공격 지시가 동시에 들어옴
3. **공격 지시 수용**: 모델이 우선순위를 잘못 판단해 공격 문장을 따름
4. **위험 행동 발생**: 민감정보를 출력하거나 외부 도구를 실행함
5. **차단과 기록**: 정책 검토와 권한 제한으로 피해를 줄임

## Ⅵ. 실무 적용 및 유의점

1. 검색 증강 생성과 브라우징 기능이 있는 서비스는 외부 문서를 신뢰 입력과 분리하고 위험 도구는 사람이 확인한 뒤에만 실행되게 하며 차단된 도구 호출 수와 민감정보 유출 재현 실패율로 확인함
2. 시스템 프롬프트를 길게 쓰는 것만으로는 방어가 되지 않으므로 읽기 전용 검색과 최소 권한 토큰을 기본값으로 두고 고권한 도구 수와 모의 우회 성공 건수로 점검함

## Ⅶ. 결론

- 프롬프트 인젝션은 모델이 텍스트를 명령처럼 받아들이는 구조에서 생기므로 문장 필터보다 입력 분리와 도구 권한 축소가 더 중요한 방어 축임
