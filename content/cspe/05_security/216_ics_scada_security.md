# 📖 【암기용】 개념 완전 이해

> 목적: ICS·SCADA 보안을 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 공장·전력·수처리 제어망을 사이버 위협과 물리 사고에서 지키는 OT 보안 체계
- **왜 필요한가**: ICS는 생산 중단 1시간이 수천만 원 손실과 안전 사고로 이어질 수 있다. IT처럼 재부팅·패치를 즉시 적용하기 어렵기 때문에 가용성·안전 우선 통제가 필요하다.
- **핵심 직관**: 사무실 PC 보안이 문서 유출 방지라면, ICS 보안은 밸브·펌프·로봇이 잘못 움직이지 않도록 명령 경로를 통제하는 일이다.

## 깊이 이해
- **배경·문제의식**: PLC·RTU·HMI·SCADA는 10~20년 수명과 24x7 운전을 전제로 설계되어 인증·암호화가 약한 Modbus, DNP3, 구형 OPC를 사용해 왔다. IT망 연결, 원격 유지보수, 스마트팩토리 전환으로 공격면이 인터넷·협력사·클라우드까지 확대됨.
- **작동 원리**: Purdue Model은 Level 0 물리공정부터 Level 5 기업망까지 계층을 나누고, IEC 62443은 Zone/Conduit로 자산군과 통신 경로를 통제한다. 방화벽·DMZ·단방향 게이트웨이·허용목록·자산 가시화·이상탐지를 조합함.
- **비유**: 병원 수술실처럼 외부 출입을 줄이고, 들어오는 사람·도구·절차를 단계별로 확인해야 한다. 멈추면 생명·설비에 영향이 있으므로 검사도 운전 조건을 깨지 않는 방식이어야 함.
- **구체 예시**: HMI가 TCP/502(Modbus)로 PLC 코일을 쓰는 현장에서 업무망 감염 단말이 같은 세그먼트에 있으면 펌프 정지 명령이 전파될 수 있다. 방안은 Level 3.5 DMZ, PLC 쓰기 명령 허용목록, 변경 승인 2인 검토임.
- **흔한 오해·주의점**: ICS 보안은 IT 보안 제품을 그대로 설치하는 과제가 아니다. 스캔 주기, 패치 창, 재기동 절차가 공정 안전·SIS·생산 계획과 맞아야 한다.

## 연결 개념
- Purdue Model - OT 계층 분리 기준
- IEC 62443 Zone/Conduit - 자산군·통신 경로 통제 모델
- OT 이상탐지 - 프로토콜 명령·공정 변수 기반 탐지

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 수치·표준·도식·문제유형 전환을 엄격히 적용한다.
> 핵심: ICS·SCADA 보안은 기밀성 중심 IT 보안이 아니라 가용성·안전·공정 무결성을 우선하는 OT 위험 통제 문제이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ICS·SCADA 보안은 PLC·RTU·HMI·SCADA 서버·Historian이 수행하는 물리 공정 제어 명령을 IEC 62443 기반으로 보호하는 체계이다.
> 2. **가치**: 가용성 99.9%, 안전 정지 절차, 무단 제어명령 차단을 통해 생산 중단·설비 파손·인명 사고를 통제한다.
> 3. **판단 포인트**: IT 보안 대책을 복사하지 말고 Purdue 계층, Zone/Conduit, 프로토콜 명령, 패치 창, 복구 절차를 함께 판단해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OT 보안과 IT 보안 차이 이해 확인 | 가용성·안전 우선, Purdue Level 0~5, Level 3.5 DMZ | CIA 순서를 IT 기준으로만 설명 |
| 산업제어 구성요소와 프로토콜 판단 확인 | PLC, RTU, HMI, SCADA, Modbus, DNP3, OPC UA | 제품명 나열 후 제어 명령 통제 누락 |
| 표준 기반 대책 수립 확인 | IEC 62443 Zone/Conduit, 자산 식별, 허용목록, 이상탐지 | 일반 방화벽·백신만 제시 |

> 요약: 이 문제는 OT 계층·프로토콜·제어명령을 안전 운전 기준으로 통제하는 설계 역량을 요구한다.

## Ⅰ. 개요 및 필요성

ICS·SCADA 보안은 산업제어시스템의 제어명령·공정데이터·운전 가용성을 보호하는 OT 보안 체계이다. 전력·제조·수처리 설비는 24x7 운전, 장비 수명 10년 이상, 패치 창 제한이 존재한다. 따라서 보안 통제는 생산 중단 시간, 안전 계장, 현장 작업 절차와 함께 설계되어야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Enterprise IT -> Level 3.5 DMZ -> SCADA/Historian -> HMI
                                   +-> PLC/RTU -> Sensor/Actuator
Policy -> IEC 62443 Zone -> Conduit -> Monitoring -> Response
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| PLC/RTU | 센서 입력 수집, 밸브·모터 제어 | Modbus/DNP3 쓰기 명령 통제 필요 |
| HMI/SCADA | 운전 화면, 알람, 제어 명령 전달 | 계정 공유·원격접속이 주요 침투 경로 |
| Historian/DMZ | 생산 데이터 저장, IT망 연계 | Level 3.5에서 양방향 통신 최소화 |
| Zone/Conduit | 자산군과 통신 경로 분리 | IEC 62443 보안 요구사항 매핑 |

> 요약: ICS 보안 구조는 Purdue 계층과 IEC 62443 Zone/Conduit를 결합해 제어명령 경로를 좁히는 방식이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산 식별 -> Purdue 계층 매핑 -> Zone/Conduit 설계
-> 프로토콜 명령 허용목록 -> 이상탐지 -> 안전 절차 기반 대응
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | PLC·RTU·HMI·서버·스위치 자산 식별 | 자산 식별률 95% 이상 |
| 2 | Purdue Level 0~5 및 Level 3.5 DMZ 매핑 | IT/OT 직접 경로 0건 |
| 3 | Modbus, DNP3, OPC UA 명령 기준 허용목록 작성 | 쓰기 명령 승인 규칙 100% |
| 4 | 네트워크 미러링 기반 이상탐지·알람 | 미승인 명령 탐지 시간 5분 이내 |
| 5 | 공정 영향 평가 후 격리·복구 | RTO 4시간, 안전정지 절차 준수 |

> 요약: ICS 보안은 자산-계층-통신-명령-대응 순서로 공정 영향을 통제한다.

## Ⅳ. 특징

| 구분 | IT 보안 | ICS·SCADA 보안 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 우선순위 | 기밀성 중심 | 가용성·안전·무결성 중심 | 생산 RTO 4시간, 안전정지 절차 |
| 변경관리 | 월간 패치 가능 | 정기 정비창 기반 패치 | 연 2~4회 계획 정비 |
| 통신 | TCP/IP, HTTP, TLS | Modbus, DNP3, OPC UA | TCP/502, 20000, 4840 |
| 통제 | EDR, DLP, IAM | Zone/Conduit, 허용목록, 단방향 연계 | IEC 62443 |

> 요약: ICS는 기밀 정보보다 제어명령 오동작과 운전 중단을 우선 통제해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | ICS·SCADA 보안 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 평면 OT망 | Purdue Level 0~5, Level 3.5 DMZ | IT/OT 직접 연결 제거 |
| 탐지 | 시그니처 IDS | 공정 변수·프로토콜 명령 이상탐지 | PLC 쓰기 명령 감시 필요 시 |
| 운영 | 즉시 패치 | 보상통제 후 정비창 패치 | 패치 재기동이 생산에 영향 시 |

> 요약: ICS 보안 선택 기준은 탐지 기능보다 공정 중단 없이 통제를 적용할 수 있는지이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 무단 제어명령 | HMI 계정 탈취, 평면망 | MFA, 점프서버, PLC 쓰기 허용목록 | 미승인 write 0건 |
| 생산 중단 | 패치·스캔으로 장비 과부하 | 수동 스캔 금지, 정비창 검증 | 장애 발생률 1% 이하 |
| 원격 유지보수 침해 | VPN 계정 공유 | PAM, 세션 녹화, 시간제 접근 | 원격 세션 감사 100% |

> 요약: OT 리스크는 침해 탐지뿐 아니라 잘못된 대응으로 생산이 멈추는 2차 피해까지 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 가용성 | 주요 공정 99.9% 이상 | DCS/SCADA 알람·가동 로그 |
| 제어명령 통제 | PLC 쓰기 명령 승인률 100% | OT IDS, 방화벽 로그 |
| 복구 | 핵심 라인 RTO 4시간 이내 | 훈련 결과, 백업 복원 기록 |

> 요약: ICS 보안 효과는 차단 건수보다 가동률, 승인 명령 비율, 복구 시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Purdue Level 3.5 DMZ 구축, Historian 단방향 전송, IT/OT 직접 세션 0건 기준 수립
2. IEC 62443 Zone/Conduit 기준으로 PLC·HMI·엔지니어링 워크스테이션 분리, TCP/502·4840 허용목록 적용
3. 정비창 패치, 백업 이미지, 오프라인 복구 훈련으로 RTO 4시간·설정 백업 주 1회 기준 운영

**결론 (2줄):**
- 기술사 판단: 안전 영향 공정이면 가용성·안전 우선 통제, 비핵심 설비이면 IT 보안 통제와 패치 자동화를 병행함
- 향후 방향: 스마트팩토리·원격운영 확대로 IEC 62443 기반 자산 가시화와 프로토콜 이상탐지가 기본 통제로 자리 잡음
