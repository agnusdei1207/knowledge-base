# 📖 【암기용】 개념 완전 이해

> 목적: SASE를 처음 보는 사람도 네트워크와 보안 기능이 왜 클라우드 엣지로 모이는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: SASE는 SD-WAN과 클라우드 보안 기능을 통합해 사용자·지점·클라우드 접속을 정책 기반으로 처리하는 아키텍처다.
- **왜 필요한가**: 원격근무, SaaS, 멀티클라우드가 늘면 모든 트래픽을 본사 보안장비로 우회시키는 구조는 지연, 비용, 정책 불일치가 커진다. SASE는 가까운 PoP에서 네트워크 연결과 보안검사를 함께 수행한다.
- **핵심 직관**: 회사마다 보안검색대를 두는 대신 전 세계 공항 허브에서 동일한 신원확인과 수하물 검사를 수행하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 전통 WAN은 지점 트래픽을 MPLS와 본사 방화벽으로 집중시켰다. SaaS와 모바일 사용자는 본사를 거치면 왕복 지연이 증가하고, 클라우드 직접접속은 정책 분산을 만든다.
- **작동 원리**: 사용자는 가장 가까운 SASE PoP에 접속하고, PoP는 신원, 단말상태, 위치, 애플리케이션, 데이터 민감도를 평가한다. 이후 SD-WAN 경로선택, SWG, CASB, ZTNA, FWaaS, DLP 정책을 한 엔진에서 적용한다.
- **비유**: 여러 도시에 흩어진 직원이 본사 출입문으로 돌아오지 않고, 가까운 보안 게이트에서 같은 출입규칙을 검증받는 구조다.
- **구체 예시**: 재택 사용자가 CRM SaaS에 접속하면 PoP가 MFA, EDR 상태, 국가, 사용자그룹을 확인하고, CASB가 다운로드 차단, DLP가 주민번호 패턴을 차단, ZTNA가 사내 ERP 접근을 앱 단위로 허용한다.
- **흔한 오해·주의점**: SASE와 SSE는 다르다. SSE는 SWG, CASB, ZTNA, FWaaS 등 보안 서비스 묶음이고, SASE는 여기에 SD-WAN 네트워크 최적화까지 포함한다.

## 연결 개념
- SD-WAN — 애플리케이션·품질 기준으로 WAN 경로 선택
- SSE — SASE 중 보안 서비스 영역, SWG/CASB/ZTNA/FWaaS 포함
- Zero Trust — 신원·기기·상황 기반 접근정책의 핵심 원칙

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SASE 답안은 SD-WAN+SSE 결합, identity/context policy, PoP 지연, data residency 리스크를 함께 다룬다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SASE는 SD-WAN과 SWG, CASB, ZTNA, FWaaS를 클라우드 PoP에서 통합 제공하는 네트워크·보안 아키텍처다.
> 2. **가치**: 사용자 위치와 네트워크 경계가 흩어진 환경에서 신원, 단말, 위치, 앱, 데이터 민감도 기반 정책을 일관되게 적용한다.
> 3. **판단 포인트**: PoP 지연시간, 데이터 거주성, 기존 VPN·MPLS 전환, SSE와 범위 차이를 도입 판단에 포함한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SASE 구성요소 이해 확인 | SD-WAN, SWG, CASB, ZTNA, FWaaS, PoP | 클라우드 방화벽 또는 VPN 대체로만 설명 |
| 원격근무·멀티클라우드 보안 판단 확인 | identity/context policy, device posture, DLP | 네트워크 경로와 보안정책 통합 누락 |
| SSE와 차이·리스크 인식 확인 | SSE는 보안영역, SASE는 SD-WAN 포함 | 지연시간·데이터 거주성 리스크 누락 |

> 요약: SASE 문제는 구성요소보다 분산 사용자 접속을 신원·상황 기반 정책으로 통합하는 구조와 리스크 판단이 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 네트워크·보안 통합 클라우드 엣지
- 배경: 원격근무, SaaS, 멀티클라우드는 본사 중심 보안장비와 MPLS 백홀 구조에서 지연, 비용, 정책 분산 문제를 만듦
- 필요성: SASE는 SD-WAN과 SWG·CASB·ZTNA·FWaaS를 PoP에서 통합하고 p95 RTT 50ms 이하, 원격사용자 정책 적용률 100% 기준으로 검증해야 함

---

## Ⅱ. 구조 및 구성요소

```text
User/Branch/Cloud -> Nearest SASE PoP
  / SD-WAN -> Path Selection -> SaaS/IaaS
  / SWG/CASB/ZTNA/FWaaS -> Policy Engine -> DLP/Logging
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SD-WAN | 애플리케이션·품질 기준 WAN 경로 선택 | MPLS, Internet, 5G 동시 사용 |
| SWG | 웹 접속 URL·악성코드·SSL 검사 | TLS inspection 정책 필요 |
| CASB | SaaS 사용 가시성·통제 | shadow IT, DLP, API 연동 |
| ZTNA | 사내 앱 접근을 사용자·기기 조건으로 허용 | 네트워크가 아닌 앱 단위 접속 |
| FWaaS/PoP | 클라우드 방화벽과 근접 처리 지점 | 지역별 PoP, 로그 보존 위치 |

> 요약: SASE는 SD-WAN 연결 기능과 SSE 보안 기능을 PoP와 정책엔진으로 통합한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접속 요청 -> 가까운 PoP 선택 -> 신원·단말·위치 평가
  -> 앱·데이터 정책 결정 -> SD-WAN 경로 선택
  -> SWG/CASB/ZTNA/FWaaS 적용 -> 로그·DLP 처리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자·지점이 지연시간 기준 PoP 접속 | PoP RTT 50ms 이하 목표 |
| 2 | 신원, MFA, 단말상태, 위치 확인 | EDR 정상, MFA 성공 |
| 3 | 앱·데이터 민감도 기반 정책 결정 | SaaS, IaaS, 내부앱 정책 분리 |
| 4 | SD-WAN 경로와 보안서비스 적용 | SWG, CASB, ZTNA, FWaaS 적용 |
| 5 | 로그·DLP·위협탐지 결과 저장 | SIEM 연계, 데이터 거주성 확인 |

> 요약: SASE는 PoP 접속 후 신원·상황 평가와 네트워크 경로 선택, 보안검사를 한 정책 흐름으로 처리한다.

## Ⅳ. 특징

| 구분 | 전통 WAN/VPN | SASE | 수치·판단 기준 |
|:---|:---|:---|:---|
| 경로 | 본사 백홀, MPLS 중심 | 근접 PoP, 인터넷+MPLS+5G | PoP RTT 50ms 이하 |
| 보안 | 본사 장비 중심 | SWG/CASB/ZTNA/FWaaS 통합 | 원격사용자 정책 적용률 100% |
| 접근 | 네트워크 단위 VPN | 앱 단위 ZTNA | 내부앱 노출 IP 0개 |
| 운영 | 장비별 정책관리 | 단일 정책엔진 | 정책 중복률 10% 이하 |

> 요약: SASE는 본사 경유 구조를 PoP 기반 정책 적용 구조로 바꾸며, 원격·클라우드 접속을 같은 기준으로 통제한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | SASE | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | VPN+MPLS+온프레미스 보안장비 | SD-WAN+SSE 클라우드 PoP | 원격사용자 30% 이상, SaaS 사용 확대 |
| 보안범위 | SWG/CASB/ZTNA 개별도입 | 통합 정책엔진과 로그 | 정책 일관성·가시성 필요 |
| SSE 구분 | SSE는 보안서비스 묶음 | SASE는 SD-WAN 포함 | WAN 전환 포함 시 SASE 선택 |

> 요약: WAN 최적화까지 필요하면 SASE, 보안 서비스 통합만 필요하면 SSE를 우선 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 지연시간 증가 | PoP 거리, TLS 검사 | 지역 PoP 검증, split policy | p95 RTT 50ms 이하 |
| 데이터 거주성 위반 | 로그·검사 데이터 해외 저장 | 리전 고정, 계약서 DPA 확인 | 국내 리전 저장률 100% |
| 벤더 종속 | 단일 정책·에이전트 의존 | 표준 로그, API, 단계적 전환 | 로그 export 100%, 해지 테스트 |

> 요약: SASE 도입 리스크는 PoP 품질, 데이터 위치, 벤더 종속이며 사전 PoC 지표로 판단한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 접속 품질 | p95 RTT 50ms 이하, 터널 가용성 99.9% | synthetic monitoring, SD-WAN 지표 |
| 정책 적용 | 원격사용자·SaaS 정책 적용률 100% | SASE 콘솔, CASB 리포트 |
| 보안 관측 | DLP 차단, 위협탐지, 로그 SIEM 연계 100% | SIEM, API 로그, 감사리포트 |

> 요약: SASE 성패는 RTT, 정책 적용률, 로그 연계율을 기준으로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 원격사용자, 지점, SaaS, IaaS 트래픽을 분류하고 PoP RTT 50ms 이하 지역에서 4주 PoC를 수행한다.
2. SD-WAN 경로정책과 SWG, CASB, ZTNA, FWaaS 정책을 사용자·기기·앱·데이터 민감도 기준으로 통합한다.
3. 로그 저장 리전, DLP 정책, SIEM 연계, 기존 VPN 단계적 축소 계획을 수립하고 데이터 거주성 요구를 계약에 반영한다.

**결론 (2줄):**
- 기술사 판단: 원격근무와 SaaS 비중이 높고 WAN 전환까지 필요하면 SASE, 보안서비스 통합만 목표이면 SSE부터 적용한다.
- 향후 방향: SASE는 Zero Trust, 브라우저 격리, AI 기반 위협탐지와 결합되어 사용자 위치와 무관한 정책 집행 플랫폼으로 발전한다.
