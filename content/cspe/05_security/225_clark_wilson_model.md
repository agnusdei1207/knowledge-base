# 📖 【암기용】 개념 완전 이해

> 목적: Clark-Wilson 모델을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 업무 데이터가 승인된 거래 절차를 통해서만 변경되도록 통제하는 상업용 무결성 모델
- **왜 필요한가**: 회계·금융·ERP 시스템은 데이터 등급보다 누가 어떤 절차로 금액·재고·계약을 바꿨는지가 핵심이다. 승인된 프로그램, 직무분리, 감사가 함께 필요하다.
- **핵심 직관**: 금고 돈은 아무 직원이 직접 고치지 못하고, 승인된 창구 업무와 2인 확인 절차를 거쳐 장부에 기록되는 방식이다.

## 깊이 이해
- **배경·문제의식**: Biba는 무결성 등급 흐름을 다루지만, 상업 시스템은 거래 절차와 내부통제가 핵심이다. Clark-Wilson은 잘 형성된 거래와 직무분리로 데이터 무결성을 유지한다.
- **작동 원리**: 보호 데이터(CDI)는 승인된 변환절차(TP)로만 변경된다. 무결성 검증절차(IVP)는 CDI가 유효 상태인지 확인하고, 직무분리와 감사로그가 부정 변경을 억제한다.
- **비유**: 은행 계좌 잔액은 DB 콘솔로 직접 수정하지 않고, 입금·출금·이체 거래 프로그램만 통과해야 장부에 반영되는 것과 같다.
- **구체 예시**: ERP에서 구매요청자는 발주 승인자가 될 수 없고, 재고 수량 변경은 승인된 TP를 통해서만 수행되며 변경 이벤트는 사용자·시간·전후 값으로 기록된다.
- **흔한 오해·주의점**: Clark-Wilson은 단순 접근통제가 아니다. 사용자가 데이터에 직접 접근하지 못하고, 검증된 업무 절차를 통해 간접 변경한다는 점이 핵심이다.

## 연결 개념
- Biba Integrity Model — 등급 기반 무결성 흐름 통제
- Separation of Duties — 요청자·승인자·처리자 역할 분리
- Audit Trail — 거래 전후 값과 행위자 기록으로 사후 검증

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CDI, UDI, TP, IVP, 직무분리, 감사의 관계를 업무 거래 무결성 관점에서 구조화한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Clark-Wilson Model은 보호 데이터가 승인된 변환절차와 직무분리를 통해서만 변경되도록 하는 상업용 무결성 모델이다.
> 2. **가치**: 회계·금융·ERP에서 직접 DB 수정, 승인 우회, 부정 거래를 well-formed transaction과 audit trail로 통제한다.
> 3. **판단 포인트**: Biba가 등급 기반 정보흐름이면 Clark-Wilson은 업무 절차, 역할 분리, 검증 절차 중심의 무결성 통제이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 상업용 무결성 모델 이해 확인 | CDI, UDI, TP, IVP, well-formed transaction | 단순 파일 권한 모델로 축소 |
| 내부통제 설계 역량 확인 | separation of duties, 승인 워크플로, 감사로그 | 직무분리·감사 누락 |
| Biba와 비교 판단 확인 | 등급 흐름 vs 거래 절차 통제 | no read down/no write up만 반복 |

> 요약: 이 문제는 업무 데이터 변경을 승인된 거래 절차와 직무분리로 통제하는 구조를 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 승인 거래 기반 무결성 통제
- 배경: 금융·회계·ERP 시스템에서 사용자가 보호 데이터(CDI)를 직접 수정하면 금액, 재고, 계약 변경의 승인 근거와 책임 추적이 끊어짐
- 필요성: CDI 변경은 TP 경유율 100%, 요청자·승인자 동일 거래 0건, 거래 전후 값 감사로그 100% 기록 기준으로 통제해야 함

---

## Ⅱ. 구조 및 구성요소

```text
User -> TP 실행 요청 -> 권한/직무분리 확인 -> CDI 변경
         / UDI 입력 검증
         / IVP 무결성 확인
         / Audit Trail 기록
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CDI | 무결성을 보장해야 하는 보호 데이터 | 계좌잔액, 재고, 원장 |
| UDI | 외부 입력·검증 전 데이터 | 주문서, 업로드 파일 |
| TP | CDI를 변경할 수 있는 승인된 변환절차 | 입금, 발주, 재고조정 |
| IVP | CDI가 유효 상태인지 검증하는 절차 | 대차 균형, 재고 음수 검증 |
| Separation of Duties | 요청·승인·처리 역할 분리 | 2인 승인, 권한 충돌 탐지 |
| Audit Trail | 거래 전후 상태와 행위자 기록 | 사용자, 시간, 전후 값 |

> 요약: Clark-Wilson은 CDI를 TP로만 변경하고 IVP, 직무분리, 감사로그로 거래 무결성을 검증한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
UDI 입력 -> TP 호출 -> 사용자 권한 확인 -> 직무분리 검증
-> CDI 변경 -> IVP 실행 -> 감사로그 저장 -> 결과 확정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | UDI 입력 수집 및 형식 검증 | 스키마·범위·서명 검증 |
| 2 | TP 실행 권한 확인 | 사용자-TP 매핑 승인 |
| 3 | 직무분리 규칙 확인 | 요청자와 승인자 분리 |
| 4 | TP가 CDI 변경 후 IVP 수행 | 대차 합계, 재고 음수 0건 |
| 5 | 거래 전후 값과 행위자 로그 저장 | 변경 로그 100% 기록 |

> 요약: 업무 데이터 변경은 입력 검증, 승인된 TP, 직무분리, IVP, 감사로그 순서로 확정된다.

## Ⅳ. 특징

| 구분 | Biba | Clark-Wilson | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 보호 방식 | 무결성 등급 기반 흐름 | 승인된 거래 절차 기반 | 금융·ERP·회계 업무 |
| 접근 형태 | 읽기·쓰기 방향 제한 | 사용자 직접 CDI 접근 금지 | TP 경유율 100% |
| 통제 수단 | no read down, no write up | TP, IVP, 직무분리, 감사 | 2인 승인, 변경로그 |
| 검증 대상 | 데이터 신뢰 등급 | 업무 규칙과 상태 일관성 | 대차 균형, 재고 음수 |

> 요약: Clark-Wilson은 데이터 등급보다 승인된 거래 절차와 내부통제로 상업용 데이터 무결성을 보장한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | DB 직접 수정·ACL | TP 경유·직무분리·감사 | 회계·재고·계약 데이터 변경 업무 |
| 비용/성능 | 개발 단순, 통제 약함 | 승인 워크플로와 로그 저장 필요 | 변경 건수 p95 처리 2초 이하 |
| 운영/위험 | 권한 남용·부정 거래 | SoD 충돌 탐지, IVP 검증 | 감사 대응과 내부회계관리 대상 |

> 요약: 업무 규칙 위반과 부정 거래 위험이 큰 시스템은 직접 접근보다 TP 기반 내부통제 구조가 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 직접 DB 수정 | 운영자 우회 접속 | break-glass 승인, DB 감사 | 콘솔 변경 0건 |
| 직무분리 충돌 | 요청자와 승인자 겸임 | SoD 룰 엔진, 권한 충돌 리포트 | 충돌 권한 0건 |
| IVP 누락 | 배치·수동 조정 경로 | IVP 공통 라이브러리, 배치 게이트 | 검증 미수행 거래 0건 |

> 요약: 직접 수정, 직무분리 충돌, 검증 누락을 DB 감사와 SoD 룰, IVP 게이트로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| TP 경유율 | CDI 변경 100% TP 경유 | DB 트리거, 애플리케이션 로그 |
| 직무분리 | 요청자·승인자 동일 거래 0건 | IAM, 워크플로 감사 |
| 감사 추적 | 거래 전후 값·행위자 100% 기록 | SIEM, DB 감사로그 |

> 요약: 적용 성과는 TP 경유율, 직무분리 위반 건수, 감사로그 완전성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 거래 경로 통제: CDI 테이블 직접 쓰기를 금지하고 모든 변경을 API/TP로 제한하며 DB 권한은 애플리케이션 서비스 계정으로 분리
2. 내부통제 구현: 요청·승인·실행 역할을 SoD 룰로 분리하고 금액 1천만원 이상 거래는 2인 승인 적용
3. 감사·검증 자동화: IVP를 배치·실시간 거래에 공통 적용하고 변경 전후 값, 사용자, 시간, 승인 ID를 SIEM에 전송

**결론 (2줄):**
- 기술사 판단: 회계·금융·ERP 시스템은 등급 기반 통제보다 Clark-Wilson의 TP·IVP·직무분리·감사 조합을 우선 적용함
- 향후 방향: SoD 룰 엔진, DB 감사, 워크플로 자동화를 결합해 내부회계관리와 보안 감사 요구를 동시에 충족함
