# 📖 【암기용】 개념 완전 이해

> 목적: 모바일 포렌식을 처음 보는 사람도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 스마트폰·태블릿의 사용자 데이터와 앱 흔적을 포렌식 절차로 수집·분석하는 활동
- **왜 필요한가**: 모바일 기기는 통화, 위치, 메신저, 인증앱, 사진 메타데이터를 포함해 사건 전후 행위를 입증하는 자료가 많다.
- **핵심 직관**: 스마트폰은 개인의 이동·대화·로그인 흔적이 모인 작은 블랙박스이다.

## 깊이 이해
- **배경·문제의식**: 모바일 증거는 잠금, 암호화, 원격 삭제, 앱별 샌드박스, 클라우드 동기화 때문에 PC 디스크보다 수집 조건이 까다롭다. NIST SP 800-101r1은 모바일 포렌식을 검증, 보존, 수집, 검사, 분석, 보고 절차로 다룬다.
- **작동 원리**: 기기 상태를 보존하고 네트워크를 차단해 원격 삭제를 막는다. 이후 논리 추출, 파일시스템 추출, 물리 추출 중 가능한 방법을 선택하고 해시·로그·도구 버전을 기록한다.
- **비유**: 잠긴 금고를 여는 것과 같다. 무리하게 열면 내용물이 바뀌거나 삭제될 수 있어, 열쇠 종류와 열기 전 상태 기록이 결과만큼 필요하다.
- **구체 예시**: iOS 기기는 BFU/AFU 상태에 따라 획득 가능한 데이터가 달라지고, Android는 버전·암호화·루팅 가능성에 따라 논리 추출과 파일시스템 추출 범위가 달라진다.
- **흔한 오해·주의점**: 모바일 포렌식은 "전체 복구"가 아니다. 앱 암호화, 삭제 데이터 덮어쓰기, 클라우드 보관 정책 때문에 획득 가능성과 분석 한계를 보고서에 써야 한다.

## 연결 개념
- 디지털 포렌식 - 체인 오브 커스터디와 해시 검증의 상위 절차
- 클라우드 포렌식 - 모바일 앱의 서버 측 데이터 확보
- MDM·MAM - 기업 모바일 단말 보안 정책과 로그 확보

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 모바일 포렌식은 단말 해제 기술이 아니라 잠금·암호화·원격삭제·클라우드 동기화 조건을 판단하는 절차이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 모바일 포렌식은 모바일 기기의 데이터와 앱 흔적을 포렌식 무결성 기준에 맞춰 수집·분석하는 디지털 포렌식 분야이다.
> 2. **가치**: 통화, 위치, 메신저, 사진 EXIF, 인증 기록을 타임라인으로 결합해 사건 행위를 입증한다.
> 3. **판단 포인트**: 기기 상태, 잠금, 암호화, 네트워크 차단, 클라우드 동기화 여부가 획득 범위와 증거성을 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 모바일 증거 특성 이해 확인 | 잠금, 암호화, 앱 샌드박스, 클라우드 동기화 | PC 포렌식 절차를 그대로 적용 |
| 획득 방식 판단 확인 | 논리, 파일시스템, 물리 추출의 범위와 한계 | 물리 추출을 항상 가능하다고 단정 |
| 증거 보존 역량 확인 | 원격삭제 차단, 전원·네트워크 상태 기록 | 기기 조작으로 알림·로그 변경 |

> 요약: 이 문제는 모바일 환경의 잠금·암호화·동기화 조건에 맞춘 획득 방식을 선택하는 능력을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 모바일 단말 증거 수집·분석 절차
- 배경: 모바일 단말은 위치, 통신, 앱, 인증 흔적을 보유하지만 암호화, 잠금, 원격삭제로 획득 가능 시간이 제한된다.
- 필요성: 논리·파일시스템·물리 획득 방식을 구분하고 해시, 시간 동기화, 보존 상태 기록으로 증거능력을 확보한다.

---

## Ⅱ. 구조 및 구성요소

```text
모바일 단말 -> 상태 보존/차단 -> 획득 도구 -> 추출 데이터
            +-> 앱/위치/통신 분석 -> 타임라인/보고서
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 단말 상태 | 전원, 잠금, OS 버전, 네트워크 연결 기록 | BFU/AFU, Android 암호화 확인 |
| 획득 방식 | 논리, 파일시스템, 물리 추출 선택 | 권한·취약점·도구 지원 여부 영향 |
| 데이터 원천 | 통화, SMS, 메신저, 위치, 사진, 브라우저 | 앱별 암호화와 클라우드 동기화 확인 |
| 분석·보고 | 타임라인, 사용자 행위, 한계 기술 | 도구 버전, 획득 범위, 해시값 포함 |

> 요약: 모바일 포렌식 구조는 단말 상태 보존, 획득 방식 선택, 앱별 분석, 한계 보고로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
권한 확인 -> 단말 촬영/상태 기록 -> 네트워크 차단 -> 획득 방식 선택
-> 데이터 추출 -> 해시/로그 저장 -> 앱 아티팩트 분석 -> 보고
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 소유자, 영장·동의, 수집 범위 확인 | 승인 문서와 사건번호 |
| 2 | 전원·잠금·시간·통신 상태 촬영 | 최초 상태 사진 3장 이상 |
| 3 | Faraday bag, 비행기 모드 등 원격삭제 차단 | 네트워크 차단 시각 기록 |
| 4 | 논리·파일시스템·물리 추출 수행 | 도구 로그와 SHA-256 기록 |
| 5 | 앱 DB, 위치, 미디어, 계정 흔적 분석 | 타임라인 재현 가능 |

> 요약: 모바일 포렌식은 상태 기록과 원격삭제 차단 후 가능한 획득 방식을 선택해 분석한다.

## Ⅳ. 특징

| 구분 | PC 포렌식 | 모바일 포렌식 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 저장 구조 | 파일시스템 중심 | 앱 샌드박스, SQLite, Keychain/Keystore | 앱별 DB·토큰 확인 |
| 획득 조건 | 디스크 분리 가능 | 잠금·암호화·배터리 영향 | BFU/AFU 상태 기록 |
| 네트워크 | 분석 중 분리 용이 | 원격 잠금·삭제 위험 | 차단 시각과 방법 기록 |
| 분석 범위 | 파일·로그 | 위치·메신저·사진 EXIF·인증앱 | 클라우드 동기화 여부 |

> 요약: 모바일 포렌식은 앱 중심 데이터와 원격삭제 리스크 때문에 단말 상태 보존이 분석보다 먼저다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | PC 디스크 이미징 | 모바일 상태 기반 추출 | 잠금·암호화·OS 버전 |
| 비용/성능 | 범용 이미징 도구 | 전문 모바일 포렌식 도구 | iOS/Android 버전 지원 |
| 운영/위험 | 네트워크 분리 후 분석 | 전원 유지와 통신 차단 동시 필요 | 원격삭제 가능성 |

> 요약: 모바일 단말은 전체 이미징보다 기기 상태에 맞춘 추출 방식 선택이 우선이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 원격삭제 | 네트워크 연결 유지 | Faraday bag, SIM 분리, Wi-Fi 차단 | 차단 시각 기록 |
| 증거 변경 | 잠금해제·앱 실행 조작 | 최초 상태 촬영, 최소 조작 원칙 | 조작 로그, 사진 기록 |
| 획득 누락 | 앱 암호화·클라우드 저장 | 앱별 저장 위치, 클라우드 영장·동의 | 추출 범위 보고서 |

> 요약: 모바일 포렌식 리스크는 원격삭제, 조작 변경, 앱별 획득 누락이며 상태 기록으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 상태 보존 | 최초 상태 사진·시간 기록 100% | 현장 체크리스트 |
| 무결성 | 추출 데이터 SHA-256 기록 100% | 도구 로그, 해시 파일 |
| 획득 범위 | 지원 앱·미지원 앱 목록 작성 | 도구 리포트 대조 |
| 보고 품질 | 분석 한계와 시간대 명시 100% | 보고서 리뷰 |

> 요약: 모바일 포렌식 품질은 상태 기록, 해시, 추출 범위, 한계 명시로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 현장 수집 시 전원·잠금·시간·통신 상태를 촬영하고 네트워크 차단 시각을 체인 오브 커스터디에 기록한다.
2. iOS/Android 버전, 암호화 상태, 도구 지원 범위를 확인해 논리 추출, 파일시스템 추출, 클라우드 자료 요청을 조합한다.
3. 앱 DB, 위치, 미디어 EXIF, 계정 로그인 흔적을 타임라인으로 통합하고 SHA-256 해시와 도구 버전을 보고서에 첨부한다.

**결론 (2줄):**
- 기술사 판단: 잠금 해제와 파일시스템 추출이 가능하면 단말 분석, 앱 서버 보관 비중이 크면 클라우드 포렌식을 병행함
- 향후 방향: 모바일 증거는 온디바이스 암호화와 E2EE 확대로 단말·클라우드·MDM 로그의 상호 검증이 필요함
