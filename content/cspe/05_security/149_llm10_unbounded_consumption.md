## 미리 알고가기

- 추론은 학습이 끝난 모델이 실제 요청에 답을 만드는 과정임
- 토큰 예산은 사용자나 서비스가 한 기간 동안 쓸 수 있는 입력·출력 토큰 한도임
- Denial of Wallet은 서비스 중단보다 과금 폭증을 노리는 공격을 말함

## Ⅰ. 개요

- **정의/개념**: LLM10 무제한 소비는 사용자나 API 키가 토큰, 요청 수, 동시 실행, 비용 한도 없이 추론을 계속 소비할 수 있어 서비스 저하와 과금 폭증을 부르는 취약점임
- **배경/필요성**: LLM 서비스는 요청 한 건의 계산 비용이 크고 자동 확장이 쉬워 통제가 느슨하면 적은 악성 사용만으로도 가용성과 비용이 함께 무너질 수 있음

## Ⅱ. 특징

- 단순 공격 기법이 아니라 공격이 성립하도록 만드는 설계 취약점에 가깝음
- 서비스 거부, 비용 폭증, 모델 추출 같은 여러 공격이 이 취약점을 발판으로 삼음
- 긴 입력, 긴 출력, 대량 반복 호출, 다계정 남용이 흔한 형태임
- 사용자별 한도와 전체 시스템 예산을 함께 두지 않으면 운영 중 뒤늦게 드러남

## Ⅲ. 종류 및 비교

| 판단 기준 | 모델 DoS | LLM10 무제한 소비 |
|:---|:---|:---|
| 의미 | 자원을 고갈시키는 공격 행위 | 그런 공격이 먹히게 만드는 통제 부재 상태 |
| 흔한 모습 | 고비용 프롬프트와 장시간 추론 | 토큰 한도 없음, 비용 상한 없음, 호출 제한 없음 |
| 주된 피해 | 지연, 장애, 비용 증가 | 지연, 장애, 비용 증가, 모델 추출 기반 제공 |
| 방어 초점 | 공격 입력 탐지 | 사용자별·서비스별 소비 한도 설계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 인증 키 | 누가 얼마만큼 호출할 수 있는지 묶는 기준임 |
| 쿼터 정책 | 요청 수, 토큰 수, 동시 실행 수 한도를 정함 |
| 비용 한도 | 일정 기간 또는 단일 요청의 최대 금액을 제한함 |
| 스케줄러 | 한 사용자가 큐를 독점하지 못하게 분산함 |
| 사용량 모니터링 | 토큰 소모와 과금과 이상 패턴을 계속 확인함 |

```text
사용자 요청 -> 인증 키 확인 -> 쿼터·비용 정책 검사 -> 추론 실행 -> 사용량 누적·차단
```

## Ⅴ. 원리 및 절차 흐름도

```text
제한 없는 호출 허용 -> 토큰과 동시 실행 누적 -> 비용과 대기열 급증 -> 정상 사용자 영향 확대 -> 차단 또는 예산 소진
```

1. **제한 없는 호출 허용**: 서비스가 느슨한 기본 설정으로 열려 있음
2. **사용량 누적**: 긴 입력과 긴 출력과 반복 호출이 계속 쌓임
3. **비용과 대기열 급증**: GPU 시간과 과금이 빠르게 늘어남
4. **정상 사용자 영향 확대**: 응답 지연과 오류가 일반 사용자에게 퍼짐
5. **예산 소진 또는 차단**: 뒤늦게 한도를 걸면 이미 피해가 난 뒤일 수 있음

## Ⅵ. 실무 적용 및 유의점

1. 공개 API와 무료 체험 서비스는 사용자별 토큰 예산과 동시 실행 수와 일일 비용 한도를 같이 둬야 하며 계정별 토큰 소모 속도와 시간당 비용 급증 건수로 점검함
2. 모델 추출이나 자동 크롤링이 의심되는 서비스는 응답 정밀도와 호출량을 함께 줄이고 비정상 장기 세션 수와 반복 질의 유사도와 차단 건수로 확인함

## Ⅶ. 결론

- LLM10은 계산 비용이 큰 서비스를 제한 없이 열어 둔 설계 문제이므로 호출 인증보다 소비 한도 설계가 먼저임
