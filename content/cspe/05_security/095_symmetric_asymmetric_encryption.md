## Ⅰ. 개요
- **정의**: 동일 키로 암복호화하는 대칭키와 공개키-개인키 쌍으로 암복호화하는 비대칭키 암호화 방식
- **배경/필요성**: 대칭키는 키 분배 문제가 있고 비대칭키는 연산 비용이 높아 상호 보완이 필요함
- **비유**: 대칭키는 같은 열쇠로 잠그고 여는 금고, 비대칭키는 우체통(공개키로 넣고 개인키로 꺼냄)

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 방식의 원리·용도 비교 | 키 분배 vs 연산 비용 트레이드오프 | 하이브리드 암호화(TLS 등) 언급 필요 |

> 요약: 대칭키의 속도와 비대칭키의 키 분배 안전성을 결합하는 하이브리드 운용이 표준임

## Ⅱ. 구성요소
```text
[평문] --> [암호화 알고리즘] --> [암호문] --> [복호화 알고리즘] --> [평문]
               |                                   |
          대칭: 동일 키                       비대칭: 키 쌍
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 대칭키 알고리즘 | AES·ChaCha20 등 동일 비밀키로 암복호화를 수행함 | 공용 열쇠 |
| 비대칭키 알고리즘 | RSA·ECC 등 공개키로 암호화하고 개인키로 복호화함 | 우체통+열쇠 |
| 키 관리 시스템 | 키 생성·저장·순환·폐기를 관리하는 인프라(HSM·KMS) | 열쇠 보관함 |
| 하이브리드 구조 | 비대칭키로 세션키를 교환한 후 대칭키로 데이터를 암호화함 | 우편+금고 |

> 요약: 대칭키는 데이터 암호화, 비대칭키는 키 교환·서명에 사용하며 하이브리드로 결합함

## Ⅲ. 절차
```text
키 교환(비대칭) --> 세션키 합의 --> 데이터 암호화(대칭) --> 복호화
```
- 1단계: 통신 당사자가 비대칭키 알고리즘으로 서로의 공개키를 교환함
- 2단계: 공개키로 세션용 대칭키(세션키)를 암호화하여 전달하고 합의함
- 3단계: 합의된 세션키로 대칭키 알고리즘을 사용하여 데이터를 암호화·전송함
- 4단계: 수신측이 동일 세션키로 복호화하고 세션 종료 시 키를 폐기함

> 요약: 비대칭키로 안전하게 세션키를 합의한 뒤 대칭키로 데이터를 암호화하는 흐름임

## Ⅳ. 문제점
- 키 분배 위험: 대칭키만 사용하면 키 전달 과정에서 탈취 위험이 존재함
- 연산 비용: 비대칭키는 대칭키 대비 100~1000배 느려 대량 데이터 암호화에 부적합함
- 양자 위협: RSA·ECC 기반 비대칭키가 양자 컴퓨터에 의해 해독될 수 있음

> 요약: 키 분배·연산 비용·양자 위협이 각 방식의 고유 약점임

## Ⅴ. 개선방안
1. 단기: 하이브리드 암호화를 표준 적용하여 키 분배 위험을 해소함
2. 중기: 하드웨어 가속(AES-NI)을 활용하여 대칭키 연산 비용을 최소화함
3. 장기: PQC(양자 내성 암호) 알고리즘으로 비대칭키를 전환하여 양자 위협에 대비함

> 요약: 하이브리드 → 하드웨어 가속 → PQC 전환으로 각 약점을 해소함

## Ⅵ. 전망
- 발전 방향: TLS 1.3에서 ECDHE+AES-GCM 조합이 표준화되고 PQC 하이브리드 모드가 시범 적용 중임
- 기술사적 판단: 대칭·비대칭의 이분법보다 용도별 적합한 알고리즘 선정 역량이 중요함
- 기술사 제언: 암호 민첩성(Crypto Agility) 확보를 위해 알고리즘 교체가 용이한 설계가 필요함
