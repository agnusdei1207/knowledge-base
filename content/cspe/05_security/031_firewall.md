# 📖 【암기용】 개념 완전 이해

> 목적: 방화벽을 처음 보는 사람도 L3/L4/L7 통제 차이를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 네트워크 경계에서 허용된 통신만 통과시키는 접근통제 장치
- **왜 필요한가**: 서버는 필요한 포트만 열어야 한다. 방화벽은 불필요한 IP·포트·애플리케이션 접근을 차단해 공격면을 줄인다.
- **핵심 직관**: 건물 출입구에서 신분증, 방문 목적, 출입 기록을 함께 확인하는 보안 게이트와 같다.

## 깊이 이해
- **배경·문제의식**: 인터넷 연결이 기본이 되면서 서버는 스캔, 무차별 대입, 취약 포트 공격에 노출된다. 모든 시스템에 개별 통제를 넣으면 정책 일관성이 깨지므로 네트워크 경계에서 공통 정책을 적용함.
- **작동 원리**: 패킷 필터는 출발지·목적지 IP와 포트를 본다. 상태기반 방화벽은 TCP 3-way handshake와 세션 테이블을 보고 응답 패킷을 허용한다. NGFW는 애플리케이션, 사용자, URL 평판, 위협 시그니처까지 확인함.
- **비유**: 패킷 필터는 주소만 보는 우편 분류, 상태기반은 접수된 민원 번호를 확인하는 창구, NGFW는 내용과 담당자 권한까지 확인하는 심사대임.
- **구체 예시**: 외부에서 내부 웹서버 `10.0.1.10:443`만 허용하고 SSH `22/tcp`는 관리망 `10.0.10.0/24`에서만 허용하면 인터넷 전체 스캔에 대한 노출 포트가 2개에서 1개로 감소함.
- **흔한 오해·주의점**: 방화벽이 있으면 침해가 사라진다는 해석은 틀림. 허용된 `443/tcp` 안의 SQL Injection, 탈취 계정 로그인, 암호화 터널 악성 트래픽은 WAF·EDR·SIEM과 함께 통제해야 함.

## 연결 개념
- NGFW: L7 애플리케이션·사용자 기반 정책으로 확장
- WAF: HTTP 요청·응답의 웹 공격 패턴 통제
- IDS/IPS: 탐지·차단 로그를 방화벽 정책 개선에 연계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 방화벽 답안은 장비 명칭 나열이 아니라 L3/L4/L7 정책 위치, 상태 테이블, 기본 차단, 룰 재인증까지 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 방화벽은 네트워크 경계에서 IP·포트·세션·애플리케이션 기준으로 허용 통신만 통과시키는 접근통제 시스템이다.
> 2. **가치**: Default Deny, 최소 허용 포트, 로그 수집으로 공격면과 비인가 접근 경로를 정량 관리한다.
> 3. **판단 포인트**: L3/L4 패킷 필터, 상태기반, NGFW의 검사 깊이와 지연시간·정책 복잡도·로그 연계 범위를 구분해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 네트워크 접근통제 원리 확인 | L3/L4/L7, ACL, State Table, Default Deny | 포트 차단 장비로만 설명하고 상태기반 처리를 누락 |
| 경계 보안 설계 역량 확인 | DMZ, 내부망 세그먼트, 관리망 분리, Rule Recertification | Any-Any 허용, 양방향 정책, 로그 보관 기준 누락 |
| 운영 통제 판단 확인 | 룰 만료일, 히트카운트, 변경 승인, SIEM 연계 | 정책 추가만 쓰고 주기적 폐기·검증을 빠뜨림 |

> 요약: 방화벽 문제는 접근통제 위치와 정책 생명주기를 함께 묻는 보안형 문제임.

---

## Ⅰ. 개요 및 필요성

방화벽은 허용 통신만 통과시키는 네트워크 접근통제 장치이다. 인터넷, DMZ, 내부망, 관리망 사이의 경계에서 공격면을 줄이고 비인가 접근을 차단한다. 정책은 최소권한·기본차단·로그감사 기준으로 설계해야 하며, 미사용 룰은 90일 단위 재검토가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
Internet -> Edge Firewall -> DMZ Server -> Internal Firewall -> App/DB
             +-> Policy Engine / State Table / Log Collector
Admin Network -> Management Interface -> Rule Change Approval
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| ACL/Rule Base | 출발지·목적지·서비스·동작 허용/차단 | Default Deny, 명시 허용 우선 |
| State Table | 세션 상태 추적 | TCP SYN, ESTABLISHED, timeout 관리 |
| Zone/Interface | Internet, DMZ, Internal, Admin 분리 | Zone 간 정책 방향성 명확화 |
| Log Collector | 허용·차단·변경 이력 수집 | SIEM 연계, 1년 이상 보관 기준 |

> 요약: 방화벽 구조는 Zone 경계, 정책 엔진, 상태 테이블, 로그 수집이 결합된 접근통제 체계임.

---

## Ⅲ. 동작원리 및 흐름도

```text
Packet In -> Zone 식별 -> Rule Match -> State Table 확인
-> Allow/Deny 결정 -> NAT/Route 처리 -> Log/SIEM 전송
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 패킷의 출발지·목적지·포트·프로토콜 식별 | RFC 791 IP, RFC 793 TCP 헤더 |
| 2 | Zone 방향과 Rule Base 매칭 | 상단 우선순위, shadow rule 탐지 |
| 3 | 세션 상태와 응답 패킷 적합성 확인 | SYN flood, half-open session 임계치 |
| 4 | 허용·차단·NAT·로깅 수행 | deny log, hit count, NAT table |

> 요약: 방화벽은 패킷 속성, 정책 순서, 세션 상태를 결합해 허용 여부를 결정함.

## Ⅳ. 특징

| 구분 | 기존/대안 | 방화벽 적용 | 판단 포인트 |
|:---|:---|:---|:---|
| 검사 계층 | Router ACL | L3/L4/L7 정책 검사 | L7 검사는 TLS 복호화 범위와 지연시간 측정 필요 |
| 정책 원칙 | 임시 허용 누적 | Default Deny, 최소권한 | Any-Any 0건, 미사용 룰 90일 검토 |
| 운영 관측 | 장비별 로그 | SIEM·NDR 연계 | 차단 이벤트, 정책 변경 이력, 관리자 계정 감사 |

> 요약: 방화벽은 단순 차단보다 정책 위치, 상태 추적, 변경 통제까지 포함할 때 채점 포인트가 완성됨.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | Router ACL | Stateful/NGFW | 세션 추적, 애플리케이션 식별 필요 시 NGFW |
| 비용/성능 | L3 ACL 지연 1ms 미만 | L7 검사·TLS 복호화 시 p95 지연 측정 | 업무 트래픽 p95 50ms 초과 여부 |
| 운영/위험 | 수동 정책 추가 | 승인·만료·히트카운트 기반 운영 | 월 1회 룰 리뷰, 변경 승인 2인 검토 |

> 요약: 방화벽 선택은 검사 깊이와 지연시간, 정책 운영 성숙도를 함께 판단해야 함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과다 허용 | 긴급 변경 후 미회수 | 만료일 필수, 90일 히트카운트 0건 룰 삭제 | Any-Any 0건, expired rule 0건 |
| 우회 통신 | 암호화 터널·비표준 포트 | App-ID, SSL inspection 예외 최소화 | unknown app 비율 5% 이하 |
| 정책 장애 | 상단 룰 충돌·NAT 오류 | 사전 시뮬레이션, rollback config | change failure rate 2% 이하 |

> 요약: 주요 위험은 정책 누적과 우회 통신이며, 만료·히트카운트·앱 식별 지표로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 공격면 | 인터넷 노출 포트 업무별 승인 목록 일치 | 외부 스캔, CMDB 대조 |
| 정책 품질 | shadow rule 0건, unused rule 90일 초과 0건 | 방화벽 정책 분석 도구 |
| 운영 보안 | 관리자 MFA 100%, 변경 로그 1년 보관 | IAM 감사, SIEM 대시보드 |

> 요약: 방화벽 성공 여부는 노출 포트, 정책 품질, 관리자 감사 지표로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 경계 설계: Internet/DMZ/Internal/Admin Zone 분리, 외부 공개 서비스는 `443/tcp` 중심 허용, 관리 포트는 VPN·관리망 IP로 제한
2. 정책 운영: Default Deny, 룰 소유자·만료일·티켓번호 필수, 90일 히트카운트 0건 룰 폐기
3. 로그 연계: deny log, admin change log, threat log를 SIEM으로 전송하고 상관분석 룰 10개 이상 운영

**결론 (2줄):**
- 기술사 판단: 단순 경계망은 상태기반 방화벽, 사용자·애플리케이션 통제가 필요한 업무망은 NGFW와 SIEM 연계를 선택함
- 향후 방향: ZTNA·SASE 환경에서도 방화벽 정책은 자산·계정·세션 로그와 결합해 지속 검증 체계로 운영해야 함
