## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 네트워크나 시스템의 악의적 행위를 탐지해 경고하는 IDS와, 이를 즉각적으로 차단하는 IPS의 보안 체계임 |
| **배경/필요성** | 방화벽을 우회하여 들어오는 정상 포트 기반의 악의적 페이로드 공격을 탐지하고 능동적으로 방어할 장치 필요 |
| **출제 의도** | 수동적 모니터링(Out-of-path)과 능동적 차단(In-line) 아키텍처의 차이 및 오탐/미탐 개념 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
| Traffic Mirroring |      |  Intrusion Detect |      | Intrusion Prevent |
| (트래픽 복제/수집)+----->| (IDS: 패턴 매칭)  +----->| (IPS: 패킷 차단)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **미러링 (SPAN/TAP)** | 실제 통신 경로 밖에서 트래픽의 복사본을 만들어 IDS에 전달하는 방식임 | 도로 옆에 서서 지나는 차들 번호판만 적기 |
| **IDS (탐지 시스템)** | 악성 패턴과 일치하면 관리자에게 경고(Alert)만 발생시키고 패킷을 놔두는 시스템임 | 도둑을 발견하고 사이렌만 울리는 경비원 |
| **IPS (방지 시스템)** | 실제 통신 경로 상(In-line)에 위치하여 악성 패킷을 식별 즉시 폐기(Drop)하는 시스템임 | 도둑을 잡고 직접 문을 닫아버리는 무장경찰 |

> 요약: 이상 징후를 발견하여 알람만 울릴 것인지(IDS), 직접 멱살을 잡고 차단할 것인지(IPS)의 아키텍처 차이임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 패킷 수집   |-->| 2. 엔진 분석   |-->| 3. 알람 발생   |-->| 4. 즉각 차단   |
| (포트/인라인)  |   | (패턴 및 이상)  |   | (IDS/IPS 공통)|   | (IPS 전용 기능)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **패킷 수집**: 스위치 포트 미러링(IDS)이나 물리적 라인 삽입(IPS)을 통해 네트워크 트래픽을 수집함
2. **엔진 분석**: 스노트(Snort) 등 탐지 엔진을 거치며 사전에 정의된 악성 시그니처 룰셋과 패킷 페이로드를 매칭함
3. **알람 발생(IDS/IPS)**: 위협이 탐지되면 통합 보안 관제(SIEM) 모니터로 위험 등급과 함께 경고 로그를 전송함
4. **즉각 차단(IPS)**: IPS의 경우 위험으로 판별된 패킷을 연결된 인터페이스로 내보내지 않고 즉시 폐기/세션 초기화(RST)함

> 요약: 패킷 수집 후 룰셋과 비교 분석을 수행하며, 모드에 따라 경고에서 멈출지 패킷 폐기까지 갈지 결정함.

## Ⅳ. 문제점
* **오탐(False Positive)의 업무 마비**: 정상적인 트래픽을 공격으로 오인하여 IPS가 차단해 버리면(가용성 침해) 기업의 핵심 서비스가 전면 중단됨
* **미탐(False Negative)의 위험성**: 아직 알려지지 않은 제로데이 공격이나 암호화된 트래픽의 경우 룰셋이 없어 공격을 통과시키는 치명적 맹점
* **인라인 모드의 성능 병목 현상**: 대규모 트래픽이 유입될 때 IPS 장비의 CPU 처리 한계로 인해 네트워크 전체에 심각한 지연(Latency)이 발생

## Ⅴ. 개선방안
* **단기 방안 (IDS 선 도입 후 IPS 전환)**: 초기 도입 시에는 모니터링(IDS) 모드로 운영하여 정상 트래픽 패턴을 튜닝(예외 처리)한 후 인라인(IPS) 모드로 전환
* **중기 방안 (가속 카드 및 SSL 검사 적용)**: 하드웨어 패턴 매칭 가속(ASIC/FPGA) 카드를 도입하고, 별도의 SSL 가시성 장비를 연동하여 암호화 위협 탐지
* **장기 방안 (AI 기반 탐지 통합)**: 시그니처 기반의 한계를 넘기 위해 머신러닝 이상 탐지 알고리즘이 결합된 AI-IPS 시스템으로 진화 적용

## Ⅵ. 전망
* 현재는 독립적인 IDS/IPS 장비를 운영하기보다 차세대 방화벽(NGFW) 내부의 핵심 기능 모듈로 통합(Consolidation)되어 운영되는 것이 업계 표준임
* 보안 관제의 자동화를 위해 SOAR 솔루션과 연동하여, 탐지(IDS) 시 방화벽 정책을 자동 수정하는 등 연동 대응 능력이 중시됨
