## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 발급자가 디지털 서명한 자격증명을 보유자 지갑에 저장하고, 검증자가 발급자와 접촉 없이 암호학적으로 진위를 검증할 수 있는 W3C 표준 데이터 포맷임 |
| **배경/필요성** | 종이 증명서의 위변조 탐지 어려움과 중앙 기관 의존 검증의 비효율을 해소하기 위해 탈중앙 디지털 증명이 필요함 |
| **출제 의도** | VC의 3자 모델(발급자-보유자-검증자)과 VP를 통한 선택적 공개를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|  발급자   | --> |  보유자   | --> |  검증자   |
| (서명발급)|     | (지갑보관)|     | (서명검증)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| VC(자격증명) | 발급자 DID로 서명된 JSON-LD 구조의 디지털 증명서임 | 위변조 방지 QR 졸업장 |
| VP(프레젠테이션) | 보유자가 VC에서 필요한 클레임만 추출·서명하여 검증자에게 제시하는 패키지임 | 졸업장에서 학위명만 제시 |
| 지갑(Wallet) | VC를 안전하게 저장·관리하고 VP를 생성하는 모바일 앱임 | 디지털 증명서 보관함 |

> 요약: 발급자(서명) → 보유자(지갑 보관·VP 생성) → 검증자(서명 검증)로 탈중앙 증명을 수행함.

## Ⅲ. 절차
```
+------------+     +------------+
| VC발급요청  | --> | 발급자서명  |
| (보유자)   |     | VC생성     |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 검증자     | <-- | VP제출    |
| 서명검증   |     | (선택공개) |
+------------+     +------------+
```

1. VC 발급 요청: 보유자가 발급자(대학·정부)에게 자격증명 발급을 요청함
2. 발급자 서명·VC 생성: 발급자가 보유자의 자격 정보를 JSON-LD로 구성하고 DID 개인키로 서명함
3. VP 제출: 보유자가 지갑에서 필요한 클레임만 선택하여 VP를 구성하고 검증자에게 제출함
4. 서명 검증: 검증자가 분산 원장에서 발급자 공개키를 조회하여 VP의 서명·만료·폐기 여부를 검증함

> 요약: 발급 → 지갑 저장 → 선택 제시 → 서명 검증으로 발급자 접촉 없이 자격을 증명함.

## Ⅳ. 문제점
- VC 폐기 어려움: 발급 후 VC를 실시간 폐기하는 표준 메커니즘이 미성숙함
- 선택적 공개 구현 난이도: ZKP 기반 선택적 공개는 연산 비용이 높고 구현이 복잡함
- 생태계 미성숙: VC 발급·검증을 지원하는 서비스·인프라가 초기 단계임

## Ⅴ. 개선방안
- (단기) Status List 활용: W3C Bitstring Status List로 VC 폐기·정지 상태를 경량 관리함
- (중기) BBS+ 서명: BBS+ 서명 체계로 ZKP 기반 선택적 공개를 구현 비용을 절감함
- (장기) 정부 주도 확산: EU eIDAS 2.0·국내 DID 사업으로 VC 생태계를 확대함

## Ⅵ. 전망
- EU 디지털 지갑·국내 모바일 신분증에 VC가 핵심 포맷으로 채택되며, BBS+ 서명 기반 프라이버시 보존 VC가 글로벌 표준으로 부상할 전망임
