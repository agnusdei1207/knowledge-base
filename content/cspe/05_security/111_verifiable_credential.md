## 미리 알고가기

- VC는 기관이 서명한 디지털 자격증명이고, DID는 그 자격증명의 주체와 발급자를 식별하는 데 자주 쓰이는 체계임
- 핵심은 문서 파일을 눈으로 보는 방식이 아니라 서명과 상태 정보를 자동 검증하는 방식이라는 점임
- 보유자는 전체 증명서를 통째로 넘기지 않고 필요한 속성만 제시할 수 있어야 실효성이 생김

## Ⅰ. 개요

- **정의/개념**: VC는 발급자가 서명한 자격 정보를 사용자가 지갑에 보관하고, 검증자가 원발급 기관에 직접 조회하지 않아도 진위와 상태를 확인할 수 있게 하는 디지털 자격증명 표준임
- **배경/필요성**: 종이 증명서나 PDF는 위변조 확인과 기관 간 재사용이 어렵고 중앙 조회 방식은 연동 비용과 과도한 정보 전달 문제가 커서 검증 가능한 디지털 자격 체계가 필요함

## Ⅱ. 특징

- 자격 정보와 발급자 증명이 함께 있어 자동 검증이 가능함
- 필요한 정보만 제시할 수 있어 프라이버시 통제가 쉬움
- 발급과 보관과 제시와 검증 역할이 분리돼 기관 간 재사용성이 높아짐
- 폐기 상태와 공통 프로파일이 정리되지 않으면 서비스 간 검증 성공률이 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전자문서 증명서 | 중앙 조회 방식 | VC |
|:---|:---|:---|:---|
| 검증 방식 | 육안 확인과 파일 진위 확인 | 발급기관 실시간 조회 | 서명과 상태 정보 검증 |
| 정보 제공 | 문서 전체 전달이 잦음 | 기관이 정한 필드 전달 | 필요한 속성만 제시 가능 |
| 재사용성 | 파일 중심 | 기관 연동 의존 | 지갑 기반 재사용 가능 |
| 주요 과제 | 자동화와 위변조 대응 약함 | 연동 비용과 장애 의존 | 폐기와 상호운용 관리 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Issuer | 사실 정보를 확인하고 VC에 서명하는 기관임 |
| Credential Claims | 학위, 자격, 성인 여부 같은 검증 대상 속성임 |
| Holder Wallet | 사용자가 VC를 저장하고 제시 범위를 통제함 |
| Proof and Status | 서명과 상태 목록으로 진위와 폐기 여부를 확인함 |
| Verifier | 제출된 정보를 검증해 허용 여부를 판단함 |

```text
발급자 확인/서명 -> 보유자 지갑 저장 -> 필요한 속성 제시 -> 검증자 서명/상태 확인
```

## Ⅴ. 원리 및 절차 흐름도

```text
자격 확인 -> VC 발급 -> 지갑 보관 -> Presentation 구성 -> 서명/상태 검증 -> 서비스 이용
```

1. **자격 확인**: 발급자가 사실 정보를 확인함
2. **VC 발급**: 서명된 자격증명을 생성함
3. **지갑 보관**: 사용자가 VC를 안전하게 저장함
4. **Presentation 구성**: 필요한 속성만 선택해 제출함
5. **검증**: 검증자가 서명과 상태 정보를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 학위·자격·출입 증명 서비스는 VC 도입 효과가 크지만 불필요한 속성 노출이 남으면 장점이 줄어드므로 선택적 공개와 상태 목록 갱신을 함께 설계하고 교차 검증 성공률과 폐기 반영 정확도로 확인함
2. 모바일 지갑 중심 운영은 사용자 경험이 중요하므로 프로파일과 복구 정책을 먼저 맞춰 지갑 간 호환성과 사용자 제출 실패율과 평균 검증 시간으로 확인함

## Ⅶ. 결론

- VC는 전자문서를 디지털 파일로 바꾸는 수준이 아니라 자격 정보를 서명과 상태 검증 기반으로 재사용 가능하게 만드는 체계임
