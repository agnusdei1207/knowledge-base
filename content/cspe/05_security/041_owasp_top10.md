## Ⅰ. 개요
- **정의**: 웹 애플리케이션의 주요 보안 위협 10가지를 선정·공개하는 표준 목록
- **배경/필요성**: 웹 취약점이 다양해지면서 조직이 우선순위를 정해 대응할 공통 기준이 필요함
- **비유**: 건강검진 체크리스트처럼, 가장 흔한 질병부터 점검하는 목록

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 10대 위협 항목과 대응 체계 이해 | 각 항목의 공격 원리와 방어 기법 | 단순 나열이 아닌 위협-대응 매핑 필요 |

> 요약: 웹 보안 위협을 우선순위화하여 체계적 방어를 가능하게 하는 표준 참조 목록임

## Ⅱ. 구성요소
```text
+-------------------+
| OWASP Top 10 List |
+---+------+--------+
    |      |
    v      v
+-------+ +----------+ +------------+
| A01   | | A02~A05  | | A06~A10    |
| Broken| | Injection| | Misc       |
| Access| | Crypto   | | Components |
+-------+ +----------+ +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| A01 Broken Access Control | 인가되지 않은 자원 접근 허용 취약점 | 잠금장치 없는 금고 |
| A03 Injection | 외부 입력이 쿼리·명령에 삽입되는 취약점 | 처방전에 가짜 약명 기입 |
| A09 Security Logging Failures | 공격 탐지·추적에 필요한 로그 부재 | CCTV 없는 건물 |

> 요약: 접근제어·인젝션·로깅 등 10개 영역을 구조화하여 점검 범위를 정의함

## Ⅲ. 절차
```text
위협 수집 -> 데이터 분석 -> 항목 선정 -> 가이드 배포
```
- 1단계: 글로벌 취약점 데이터 수집 — CWE 매핑 기반 사고 사례 집계
- 2단계: 발생 빈도·영향도 기반 통계 분석 수행
- 3단계: 상위 10개 위협 항목 선정 및 순위 확정
- 4단계: 항목별 설명·대응 가이드 문서화 후 공개 배포

> 요약: 데이터 기반 분석으로 상위 10개 위협을 선정하고 대응 가이드를 배포하는 절차임

## Ⅳ. 문제점
- 갱신 주기 지연: 3~4년 간격 갱신 — 신규 위협 반영이 느림
- 조직 맞춤 부재: 범용 목록 — 산업·환경별 특수 위협을 반영하지 못함
- 형식적 적용: 체크리스트만 확인 — 근본 원인 분석 없이 통과 처리됨

> 요약: 갱신 주기·범용성·형식적 적용이 실효성을 저하시키는 요인임

## Ⅴ. 개선방안
1. 단기: 조직별 위협 인텔리전스와 연계하여 보완 항목 추가
2. 중기: CI/CD 파이프라인에 OWASP 기반 자동 스캔 도구 통합
3. 장기: 실시간 위협 데이터 피드백으로 동적 위협 목록 운영 체계 구축

> 요약: 자동화·맞춤화·실시간화를 통해 목록의 실효성을 높이는 방향임

## Ⅵ. 전망
- 발전 방향: API·클라우드·AI 관련 위협 항목이 지속 확대될 것임
- 기술사적 판단: 보안 거버넌스의 기준선으로서 활용 가치가 유지됨
- 기술사 제언: OWASP 목록을 기반으로 조직 고유 위협 모델과 결합하여 운영할 것을 제언함
