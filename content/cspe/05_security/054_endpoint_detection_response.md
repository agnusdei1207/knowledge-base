## Ⅰ. 개요
- **정의**: 엔드포인트에서 프로세스·파일·레지스트리 활동을 실시간 수집하여 위협을 탐지·대응하는 솔루션임
- **배경/필요성**: 시그니처 기반 안티바이러스로는 파일리스 공격·제로데이 등 신종 위협 탐지가 곤란함
- **비유**: 집 안에 설치된 행동 감지 센서가 침입자의 동선을 추적하고 자동으로 문을 잠그는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엔드포인트 행동 기반 탐지 원리 | 에이전트 기반 실시간 텔레메트리 수집 | AV(시그니처 매칭) vs EDR(행동 분석+대응) 차이 명시 |

> 요약: EDR은 엔드포인트 행동 데이터를 실시간 분석하여 신종 위협을 탐지·격리하는 기술임

## Ⅱ. 구성요소
```text
[Endpoint Agent] --> [Cloud/On-prem Server] --> [Detection] --> [Response]
      |                      |                      |
      v                      v                      v
  텔레메트리수집         중앙저장/분석          격리/복구
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 에이전트 | 엔드포인트에 설치되어 프로세스·네트워크·파일 이벤트를 수집함 | 현장 경비원 |
| 중앙 서버 | 에이전트 텔레메트리를 수집·저장하고 분석 엔진을 실행함 | 통합 관제실 |
| 탐지 엔진 | IOC 매칭·행동 분석·ML 모델로 악성 활동을 식별함 | 이상 행동 판별기 |
| 대응 모듈 | 프로세스 종료·네트워크 격리·파일 격리를 원격 실행함 | 자동 잠금 장치 |

> 요약: 에이전트 -> 중앙 서버 -> 탐지 -> 대응의 4개 구성요소로 이루어짐

## Ⅲ. 절차
```text
수집 --> 전송 --> 탐지 --> 대응
 |        |        |        |
 v        v        v        v
이벤트   중앙적재  행동분석  격리/복구
```
- 1단계: 수집 — 에이전트가 프로세스 생성·파일 변경·네트워크 연결 이벤트를 기록함
- 2단계: 전송 — 텔레메트리를 중앙 서버로 실시간 또는 배치 전송함
- 3단계: 탐지 — IOC·MITRE ATT&CK TTP 매핑·ML 모델로 악성 여부를 판별함
- 4단계: 대응 — 위협 확인 시 프로세스 종료·네트워크 격리·악성 파일 삭제를 수행함

> 요약: 이벤트 수집, 중앙 전송, 행동 기반 탐지, 원격 격리/복구 순서로 동작함

## Ⅳ. 문제점
- 에이전트 성능 영향: 실시간 모니터링으로 엔드포인트 CPU/메모리 사용량 증가함
- 오프라인 탐지 공백: 네트워크 미연결 시 중앙 서버 기반 분석이 불가함
- 에이전트 우회 공격: 커널 레벨 루트킷이 에이전트 프로세스를 무력화할 수 있음

> 요약: 성능 부하, 오프라인 공백, 에이전트 우회가 주요 과제임

## Ⅴ. 개선방안
1. 단기: 에이전트 경량화 및 이벤트 필터링으로 엔드포인트 부하 최소화 필요
2. 중기: 로컬 ML 모델 탑재로 오프라인 환경에서도 자체 탐지 가능하게 설계 필요
3. 장기: 하드웨어 기반 무결성 검증(TPM 연동)으로 에이전트 보호 강화 필요

> 요약: 경량화, 로컬 ML, 하드웨어 무결성 검증으로 단계적 개선 가능함

## Ⅵ. 전망
- 발전 방향: XDR(053 참조) 플랫폼의 엔드포인트 텔레메트리 채널로 통합되는 추세임
- 기술사적 판단: 원격 근무 확대로 엔드포인트 보안 수요가 지속 증가할 전망임
- 기술사 제언: NDR(052 참조)·UEBA(051 참조)와 연계하여 다계층 탐지 체계를 설계해야 함
