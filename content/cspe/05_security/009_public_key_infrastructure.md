## 미리 알고가기

- PKI: 공개키와 주체 신원을 인증서로 연결하고 검증하는 기반구조임
- CA: 인증서를 발급하고 서명하는 인증기관임
- RA: 인증서 발급 전 가입자 신원을 확인하는 등록기관임
- 인증서 체인: 루트 CA에서 최종 인증서까지 이어지는 서명 경로임
- 폐지 확인: CRL 또는 OCSP로 인증서 유효 상태를 확인하는 절차임

## Ⅰ. 개요

- **정의/개념**: PKI는 공개키 소유자 신원을 인증서, CA, 폐지 검증 절차로 관리하는 신뢰 인프라임
- **배경/필요성**: 공개키는 누구나 만들 수 있으므로 해당 공개키가 특정 주체의 것인지 검증할 체계가 필요함

## Ⅱ. 특징

- 신뢰는 루트 CA에서 중간 CA와 최종 인증서로 위임됨
- 인증서 검증은 서명 검증, 기간 확인, 도메인·주체 확인, 폐지 확인을 포함함
- CA 개인키 유출은 하위 인증서 신뢰에 직접 영향을 줌
- PKI 운영은 발급보다 갱신, 폐지, 감사가 더 자주 문제 됨

## Ⅲ. 종류 및 비교

| 구분 | 공인 PKI | 사설 PKI |
|:---|:---|:---|
| 신뢰 범위 | 브라우저·OS 신뢰 저장소 | 조직 내부 신뢰 저장소 |
| 적용 | 공개 웹, 전자거래 | 내부망, 장비 인증, mTLS |
| 장점 | 외부 사용자 검증 용이 | 정책과 발급 절차 통제 |
| 주요 위험 | CA 생태계 의존 | 루트 배포와 폐지 전파 부담 |
| 적용 판단 | 대외 서비스 | 내부 서비스·기기 인증 |

> 요약: PKI는 인증서 발급뿐 아니라 신뢰 저장소와 폐지 검증까지 포함해야 완성됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| Root CA | 최상위 신뢰 기준 |
| Intermediate CA | 발급 권한을 위임받은 중간 인증기관 |
| RA | 가입자 신원과 발급 요청 확인 |
| 인증서 저장소 | 발급 인증서와 체인 정보 제공 |
| CRL·OCSP | 인증서 폐지 상태 확인 |

```text
Root CA -> Intermediate CA -> End-Entity Certificate -> 사용자·서버·기기
                         |
                         +-> CRL/OCSP 폐지 상태
```

## Ⅴ. 원리 및 절차 흐름도

1. **신원 확인**: RA 또는 CA가 신청자의 통제권과 신원을 확인함
2. **키 생성**: 가입자가 키쌍을 만들고 CSR을 제출함
3. **인증서 발급**: CA가 공개키와 주체 정보를 서명함
4. **배포·사용**: 서버나 사용자가 인증서를 제시함
5. **검증·폐지**: 상대가 체인, 기간, 이름, 폐지 상태를 확인함

## Ⅵ. 실무 적용 및 유의점

- 루트 CA는 오프라인 보관과 엄격한 접근 통제가 필요함
- 중간 CA를 분리하면 루트 키 노출 위험과 발급 업무가 분리됨
- 인증서 자동 갱신은 장애를 줄이지만 발급 권한 통제를 함께 설계해야 함
- mTLS는 클라이언트 인증서까지 검증해 서비스 간 신원을 확인함
- PQC 전환은 인증서 크기, 체인 길이, 검증 성능에 영향을 줌

## Ⅶ. 결론

- PKI는 공개키 자체가 아니라 공개키와 주체의 관계를 검증하는 운영 구조임
- 답안에서는 CA, 인증서 체인, 폐지 확인, 키 보호를 같은 흐름으로 써야 함

## 작성 근거(검토용)

- PKI를 단순 “제3자 보증”으로 쓰지 않고 검증 절차와 운영 요소로 풀어냄
- 공인·사설 PKI 비교는 적용 범위와 신뢰 저장소 차이를 중심으로 구성함
- 010~012번 인증서, CA, 폐지 문서와 중복되지 않게 전체 구조를 담당하게 함
