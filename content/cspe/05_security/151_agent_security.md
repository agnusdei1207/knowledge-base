## 미리 알고가기

- 에이전트는 모델이 여러 단계로 계획을 세우고 도구를 호출해 실제 행동까지 수행하는 구조임
- 가드레일은 위험한 입력과 출력과 행동을 제한하는 정책 계층임
- 최소 권한은 사용자와 도구에 꼭 필요한 범위의 권한만 주는 원칙임

## Ⅰ. 개요

- **정의/개념**: 에이전트 보안은 계획 수립, 도구 호출, 권한 전달, 실행 결과 검토를 통제해 에이전트의 위험 행동을 막는 체계임
- **배경/필요성**: 에이전트는 메일 발송, 파일 수정, 결제 승인 같은 실제 행동을 수행함. 한 번의 오판이 시스템 변경으로 이어질 수 있음

## Ⅱ. 특징

- 프롬프트 보안과 인프라 보안과 권한 통제를 함께 묶어 봐야 함
- 사용자 문맥을 잃으면 모델이 남의 권한으로 행동하기 쉬움
- 도구 수가 많고 단계가 길수록 검증 지점이 더 필요함
- 가드레일만으로 충분하지 않아 승인 절차와 감사 로그가 함께 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 챗봇 | 에이전트 기반 서비스 |
|:---|:---|:---|
| 주된 결과 | 답변 생성 | 답변과 실제 작업 실행 |
| 권한 중요도 | 주로 정보 노출 통제 | 파일, 메일, 결제, DB 권한 통제가 핵심 |
| 위험 범위 | 잘못된 답변 | 잘못된 답변과 실제 시스템 변경 |
| 방어 초점 | 입력 필터와 출력 검토 | 권한 문맥, 도구 범위, 승인 절차 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 신원 | 누가 요청했는지와 어떤 권한이 있는지 정함 |
| 계획 모델 | 어떤 도구를 어떤 순서로 쓸지 결정함 |
| 도구 목록 | 읽기, 쓰기, 전송, 삭제 같은 실제 기능을 제공함 |
| 정책 엔진 | 역할별 허용 범위와 금지 행동을 판단함 |
| 감사 로그 | 누가 어떤 지시로 무엇을 실행했는지 남김 |

```text
사용자 요청 -> 계획 모델 -> 도구 선택 -> 정책 엔진 검토 -> 실행 -> 감사 로그
```

## Ⅴ. 원리 및 절차 흐름도

```text
신원 확인 -> 작업 계획 수립 -> 도구와 권한 매핑 -> 실행 전 검토 -> 실행과 기록 -> 이상 행위 점검
```

1. **신원 확인**: 요청 사용자와 세션 권한을 확인함
2. **작업 계획 수립**: 에이전트가 필요한 도구와 순서를 정함
3. **권한 매핑**: 사용자 권한에 맞는 토큰과 범위를 붙임
4. **실행 전 검토**: 고위험 작업은 정책이나 사람 승인을 거침
5. **실행과 기록**: 실제 동작과 결과를 로그로 남겨 재검토함

## Ⅵ. 실무 적용 및 유의점

1. 사내 업무 에이전트는 사용자별 권한 토큰을 쓰고 삭제·발송·결제는 승인 절차를 붙여 정책 거부 건수와 무권한 도구 접근 시도로 점검함
2. 코드 실행과 파일 조작 에이전트는 읽기와 쓰기 권한을 분리하고 모의 탈옥 시험을 돌려 승인 없는 변경 건수로 확인함

## Ⅶ. 결론

- 에이전트 보안의 핵심은 모델을 믿는 일이 아니라 권한과 실행 경로를 잘게 나눠 피해 반경을 줄이는 일임
