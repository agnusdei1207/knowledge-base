# 📖 【암기용】 개념 완전 이해

> 목적: PAM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: PAM은 root, Administrator, DB admin, 클라우드 Owner 같은 특권 계정의 발급·사용·기록·회수를 통제하는 체계임
- **왜 필요한가**: 일반 계정이 침해되어도 피해 범위는 제한되지만, 특권 계정이 침해되면 시스템 설정 변경, 로그 삭제, 데이터 대량 유출이 가능하다.
- **핵심 직관**: 금고 열쇠를 개인 책상에 두지 않고, 금고실에서 승인받아 잠깐 빌리고 사용 장면을 녹화한 뒤 반납하는 방식임

## 깊이 이해
- **배경·문제의식**: 운영자는 장애 대응 때문에 높은 권한을 필요로 한다. 그러나 상시 관리자 권한, 공유 root 비밀번호, 장기 SSH Key는 침해 시 횡적 이동과 권한 상승의 통로가 된다.
- **작동 원리**: 특권 계정을 Vault에 보관하고 사용자는 승인 후 JIT/JEA 방식으로 제한된 시간과 명령 범위만 부여받는다. 세션은 Proxy를 거쳐 기록되고 명령어, 파일 전송, DB 쿼리를 감사한다.
- **비유**: 병원 마약류 보관함처럼 사용 목적, 승인자, 사용량, 시간, 반납 기록을 남기는 통제 절차와 같음
- **구체 예시**: 운영자가 운영 DB 점검을 요청하면 30분 TTL의 임시 계정을 발급하고, SQL 세션을 녹화하며, 작업 종료 후 비밀번호를 자동 순환함
- **흔한 오해·주의점**: PAM은 비밀번호 금고만이 아니다. JIT 권한, 세션 프록시, 명령 통제, Break-glass, 비밀키 순환을 포함해야 함

## 연결 개념
- IAM — 일반 신원과 인증의 기반, PAM은 특권 계정에 집중
- Least Privilege — 필요한 시간·범위만 권한을 부여하는 원칙
- Zero Trust — 관리자 접근도 매 요청 검증과 세션 감사를 요구

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PAM은 금고 제품 설명이 아니라 특권 계정 식별, 승인, JIT 부여, 세션 감사, 비상 접근 통제를 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PAM은 고위험 특권 계정의 사용 권한과 세션을 통제해 권한 남용과 침해 확산을 줄이는 보안 체계이다.
> 2. **가치**: 상시 관리자 권한을 제거하고 JIT 권한, 세션 녹화, 비밀번호 순환으로 책임 추적성을 확보한다.
> 3. **판단 포인트**: Vault, Access Broker, Session Proxy, Approval Workflow, Break-glass를 함께 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 특권 계정 위험 이해 확인 | root, Administrator, DB admin, Cloud Owner, CI/CD secret | 일반 IAM과 PAM을 구분하지 않음 |
| 접근 통제 구조 확인 | Vault, JIT/JEA, Session Proxy, MFA, 승인 워크플로 | 비밀번호 저장 기능만 기술 |
| 감사·비상 운영 판단 확인 | 세션 녹화, 명령 감사, Break-glass, 사후 검토 | 장애 대응 계정 통제 누락 |

> 요약: PAM 답안은 특권 계정 사용 시간을 줄이고, 사용 순간을 승인·기록·회수하는 구조를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

PAM은 특권 계정 접근을 승인·집행·감사하는 보안 체계이다.
특권 계정은 시스템 설정 변경, 로그 삭제, 데이터 반출 권한을 가지므로 침해 시 업무 영향과 규제 리스크가 크다.
상시 권한을 JIT 권한으로 바꾸고 세션을 기록해 권한 남용과 침해 확산을 통제해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Admin User -> MFA/Approval -> PAM Broker -> Target System
                              |        |
                              +-> Vault
                              +-> Session Recording -> SIEM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Vault | 특권 비밀번호, SSH Key, API Secret 보관·순환 | AES-256, HSM, 90일 순환 |
| Access Broker | 요청 승인, JIT 계정 발급, 권한 범위 제한 | TTL 30분, JEA 명령 세트 |
| Session Proxy | RDP, SSH, SQL 세션 중계·녹화 | 명령어 차단, 파일 전송 기록 |
| Approval Workflow | 작업 사유, 승인자, 티켓 번호 확인 | 2인 승인, Change Ticket 연계 |
| Break-glass | 장애 시 비상 접근 제공 | 사후 24시간 내 검토 |

> 요약: PAM은 Vault에 자격증명을 격리하고 Broker와 Proxy를 통해 특권 사용을 시간·명령·세션 단위로 제한한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Privileged Request -> MFA -> Approval -> JIT Credential
-> Session Proxy -> Command/Screen Record -> Credential Rotation
-> Audit Review
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 특권 작업 요청과 변경 티켓 제출 | 작업 사유, 대상, 시간 범위 필수 |
| 2 | MFA와 승인 워크플로 수행 | 관리자 MFA 100%, 승인자 분리 |
| 3 | JIT 계정 또는 임시 Secret 발급 | TTL 30분, 범위 제한 명령 |
| 4 | Proxy를 통한 세션 중계와 명령 기록 | 녹화 누락 0건, 금지 명령 차단 |
| 5 | 작업 종료 후 자격증명 순환과 사후 검토 | 24시간 내 리뷰, SIEM 전송 |

> 요약: PAM은 접근 전 승인, 접근 중 세션 통제, 접근 후 자격증명 회수와 감사로 동작한다.

## Ⅳ. 특징

| 구분 | 기존 관리자 운영 | PAM | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 권한 보유 | 상시 admin 권한 | JIT/JEA 임시 권한 | TTL 30분, 명령 세트 제한 |
| 자격증명 | 공유 root 비밀번호 | Vault 보관·자동 순환 | 90일 이하 순환, 공유 계정 0개 |
| 세션 기록 | OS 로그 일부 확인 | 화면·명령·파일 전송 기록 | 녹화 보존 1년 이상 |
| 비상 접근 | 개인 관리자 계정 사용 | Break-glass 승인·사후 검토 | 24시간 내 사후 승인 |

> 요약: PAM은 특권 권한의 보유 시간을 줄이고 사용 행위를 세션 단위로 추적하는 점이 일반 IAM과 다르다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 공유 admin 계정 | 개인 신원+PAM Proxy+Vault | root 공유 계정이 존재하면 우선 도입 |
| 비용/운영 | 직접 접속 허용 | 승인·녹화·순환 절차 추가 | 운영 DB, AD, Cloud Owner부터 단계 적용 |
| 통제 | 사후 로그 분석 | 사전 승인+실시간 명령 통제 | 개인정보·금융·운영망 필수 통제 |

> 요약: PAM은 모든 서버보다 고위험 특권 계정부터 적용하고, 운영 부담은 JIT 자동화로 상쇄해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 우회 접속 | 직접 SSH/RDP 경로 허용 | 방화벽·Bastion 강제, PAM 외 접속 차단 | PAM 우회 접속 0건 |
| Vault 단일 장애 | 중앙 금고 장애 | HA 구성, DR Vault, 오프라인 봉인 키 | RTO 30분, 복구 훈련 반기 1회 |
| 과도한 예외 | 비상 계정 남용 | Break-glass 사유 코드와 24시간 리뷰 | 비상 접근 월 3건 이하 |

> 요약: PAM 리스크는 우회 경로, 금고 장애, 예외 남용이므로 네트워크 강제와 사후 검토를 같이 둔다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 특권 계정 커버리지 | Tier-0 계정 100%, 운영 DB 95% 이상 | 계정 인벤토리, PAM 등록 현황 |
| 세션 감사 | 녹화 누락 0건, 명령 로그 100% 수집 | PAM 리포트, SIEM 대조 |
| 자격증명 관리 | 공유 계정 0개, Secret 90일 이하 순환 | Vault 리포트, Secret Scan |

> 요약: PAM 도입 효과는 특권 계정 커버리지, 세션 감사 완전성, Secret 순환률로 판정한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AD Domain Admin, Cloud Owner, 운영 DB 계정을 Tier-0으로 분류하고 PAM 등록률 100%를 1차 목표로 설정
2. 운영 접근은 MFA, 변경 티켓, 2인 승인, TTL 30분 JIT 권한으로 제한하고 직접 SSH/RDP를 방화벽에서 차단
3. 세션 녹화와 명령 로그를 SIEM에 전송하고 Break-glass 사용은 24시간 내 사후 검토로 종결

**결론 (2줄):**
- 기술사 판단: 일반 계정은 IAM으로 관리하고, 시스템 장악 권한을 가진 계정은 PAM으로 별도 격리함
- 향후 방향: 사람 관리자 중심 PAM에서 Kubernetes, CI/CD, Cloud API Secret까지 특권 범위가 확대됨
