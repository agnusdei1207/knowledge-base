## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | ITU-T에서 제정한 공개키 인증서의 표준 형식으로, 주체와 공개키를 암호학적으로 결합한 데이터 구조임 |
| **배경/필요성** | 다양한 시스템과 프로토콜(TLS 등)에서 상호 운용 가능한 통일된 형태의 디지털 신분증 포맷 필요 |
| **출제 의도** | 인증서의 필수 필드(버전, 일련번호, 주체, 유효기간)와 서명 알고리즘의 구조 파악 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Basic Fields     |      |  Extensions (v3)  |      |   CA Signature    |
| (버전, 주체, 키)  +----->| (키 용도, 제약)   +----->| (무결성 보증 서명)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **기본 필드 (Basic Fields)** | 일련번호, 서명 알고리즘, 발행자(Issuer), 주체(Subject), 유효기간 등 필수 정보임 | 여권의 성명, 생년월일, 만료일 |
| **공개키 정보 (Public Key)** | 소유자의 공개키와 이를 사용하는 알고리즘(RSA, ECC 등) 명세임 | 여권 소유자의 사진과 지문 |
| **CA 서명 (Signature)** | 앞선 모든 데이터를 해싱한 후 CA의 개인키로 암호화한 전자서명 값임 | 외교부의 위조 방지 홀로그램 |

> 요약: 주체 정보와 공개키를 묶어 CA가 서명한 국제 표준 규격의 디지털 신원 보증서임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 데이터 인코딩|-->| 2. 해시 추출   |-->| 3. CA 서명 적용|-->| 4. 인증서 완성 |
| (ASN.1 규격화) |   | (전체 필드 대상)|   | (CA 개인키 이용)|   | (X.509 형식)   |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **데이터 인코딩**: 인증서에 들어갈 각종 필드를 ASN.1 표준 문법을 사용하여 구조화된 데이터로 직렬화함
2. **해시 추출**: 구조화된 인증서 본문 전체(TBSCertificate)에 대해 SHA-256 등의 알고리즘으로 해시값을 도출함
3. **CA 서명 적용**: 도출된 해시값을 인증 기관(CA)의 최상위/중간 개인키로 비대칭 암호화함
4. **인증서 완성**: 서명값을 인증서 구조의 끝에 덧붙여 완전한 X.509 v3 인증서 포맷을 생성함

> 요약: 표준화된 양식으로 데이터를 작성하고, 그 위에 기관 서명을 덮어씌워 무결성과 호환성을 확보함.

## Ⅳ. 문제점
* **포맷의 유연성 부족 및 파싱 오류**: ASN.1 파싱의 복잡성으로 인해 구현체별 취약점이나 버퍼 오버플로우가 빈번히 발생함
* **확장 필드 남용**: v3 확장 필드의 비표준 사용으로 상호 호환성이 저하되고 인증서 크기가 과도하게 커질 우려가 있음
* **인증서 탈취 및 도용**: X.509 인증서 파일(.pfx 등) 자체가 탈취될 경우, 패스워드가 약하면 개인키가 유출되어 심각한 피해 발생

## Ⅴ. 개선방안
* **단기 방안 (파서 검증)**: 엄격하게 검증된 최신 SSL/TLS 라이브러리(OpenSSL, BoringSSL 등)를 사용하여 ASN.1 파싱 취약점 원천 차단
* **중기 방안 (표준 프로파일 준수)**: RFC 5280 규격에 맞는 필수 확장 필드만 사용하여 상호 운용성과 경량화 달성
* **장기 방안 (모바일 신분증 전환)**: 하드웨어 보안 요소(SE)나 TEE를 결합한 W3C 분산 신원(DID) 등 차세대 포맷과 병행 또는 전환

## Ⅵ. 전망
* 현재 모든 웹 생태계(HTTPS)의 근간이지만, 구문이 지나치게 복잡하여 간소화된 인증서 포맷에 대한 연구가 계속되고 있음
* 양자내성암호(PQC) 시대 도입 시 서명값과 키 길이가 대폭 커져, X.509 크기 팽창 문제를 해결하기 위한 표준 업데이트가 필수적임
