## 미리 알고가기

- MAC: 비밀키를 아는 당사자만 만들 수 있는 메시지 인증 코드임
- HMAC: 해시 함수와 비밀키를 결합한 MAC 구성임
- ipad·opad: HMAC 내부와 외부 해시에 쓰는 패딩 상수임
- 길이 확장 공격: 일부 해시 구조에서 `Hash(key || message)` 형태를 확장할 수 있는 공격임
- 상수 시간 비교: 값 차이에 따른 처리 시간 차이를 줄이는 비교 방식임

## Ⅰ. 개요

- **정의/개념**: HMAC은 비밀키와 해시 함수를 두 단계로 결합해 메시지 무결성과 송신자 보유 키를 확인하는 MAC임
- **배경/필요성**: 단순 해시는 공개 입력만으로 다시 계산됨. 공유 비밀키를 아는 당사자만 인증값을 만들 절차가 필요함

## Ⅱ. 특징

- 해시값이 아니라 비밀키 기반 인증 태그를 생성함
- 송신자와 수신자가 같은 키를 보유해야 검증이 가능함
- 해시 함수의 압축 구조를 그대로 쓰되 내부·외부 해시로 감쌈
- 부인방지는 제공하지 않으므로 전자서명과 역할이 다름

## Ⅲ. 종류 및 비교

| 구분 | 단순 해시 | HMAC | 전자서명 |
|:---|:---|:---|:---|
| 키 사용 | 없음 | 공유 비밀키 | 개인키·공개키 |
| 확인 대상 | 데이터 동일성 | 무결성, 키 보유자 | 무결성, 서명자 |
| 검증 주체 | 누구나 계산 가능 | 같은 키 보유자 | 공개키 보유자 |
| 부인방지 | 없음 | 없음 | 제공 가능 |
| 적용 판단 | 파일 체크섬 | API 요청 인증 | 계약·인증서·코드 서명 |

> 요약: HMAC은 단순 해시에 키 보유 검증을 더하지만 공개 검증과 부인방지는 제공하지 않음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 메시지 | 인증 대상 데이터 |
| 비밀키 | 송수신자가 공유하는 인증 기준 |
| 해시 함수 | 내부·외부 다이제스트 계산 |
| ipad·opad | 키를 두 해시 단계에 다르게 주입 |
| HMAC 값 | 수신자가 비교할 인증 태그 |

```text
K xor ipad + M -> Hash -> inner
K xor opad + inner -> Hash -> HMAC
```

## Ⅴ. 원리 및 절차 흐름도

1. **키 준비**: 공유 비밀키를 블록 길이에 맞게 보정함
2. **내부 해시**: `K xor ipad`와 메시지를 해시함
3. **외부 해시**: `K xor opad`와 내부 해시값을 다시 해시함
4. **태그 전송**: 메시지와 HMAC 값을 함께 전달함
5. **검증 비교**: 수신자가 같은 방식으로 계산해 상수 시간으로 비교함

## Ⅵ. 실무 적용 및 유의점

- API 요청 인증은 메서드, 경로, 시간값, 본문 해시를 서명 입력에 포함함
- 키가 양측에 공유되므로 키 유출 시 양측 모두 위조 가능성이 생김
- 태그 비교는 시간 차이로 부분 일치 정보를 주지 않게 구현함
- HMAC-SHA-256은 JWT HS256, 웹훅 검증, 메시지 인증에 사용됨
- 장기 키는 KMS와 교체 주기로 관리함

## Ⅶ. 결론

- HMAC은 해시의 무결성 검증에 공유 비밀키 기반 인증을 더한 구조임
- 답안에서는 “해시보다 안전”이 아니라 검증 주체와 부인방지 한계를 구분해야 함

## 작성 근거(검토용)

- 기존 비유와 감정적 표현을 제거하고 HMAC의 두 단계 해시 구조를 중심에 둠
- 단순 해시, HMAC, 전자서명 비교로 역할 혼동을 줄임
- 기존 단정 표현 대신 키 보유 검증과 키 유출 조건을 함께 제시함
