## 미리 알고가기

- NVD는 CVE 정보를 확장해 CVSS, CPE, CWE, 참조 링크 같은 운영 메타데이터를 제공하는 공개 취약점 데이터베이스임
- CVE가 취약점 이름표라면 NVD는 영향 제품과 점수와 약점 유형을 붙여 주는 해설서에 가까움
- NVD 데이터는 자동화에 유용하지만 공급자 권고나 실제 환경 검증을 대신하지는 못함

## Ⅰ. 개요

- **정의/개념**: NVD는 공개된 CVE 항목에 대해 영향 제품 식별 정보, CVSS 점수, CWE 약점 분류, 참조 자료를 구조화해 제공하는 취약점 메타데이터 데이터베이스임
- **배경/필요성**: 취약점 수가 많아 사람이 벤더 공지를 일일이 읽어 영향 자산을 분류하기 어렵기 때문에 스캐너와 자산 관리와 패치 프로세스가 공통으로 사용할 구조화된 데이터가 필요함

## Ⅱ. 특징

- CVE 정보를 자산 식별과 우선순위 판단에 쓰기 쉬운 형태로 확장해 줌
- CPE와 CWE와 CVSS를 함께 제공해 제품 식별과 약점 분류와 위험도 분석을 돕음
- 자동화 연계에 적합하지만 CPE 매칭 오류나 분석 지연 가능성이 있음
- 조직은 NVD를 기본 데이터로 쓰되 공급자 권고와 SBOM과 내부 자산 정보를 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | CVE 목록 | NVD |
|:---|:---|:---|
| 제공 핵심 | 취약점 식별자와 기본 설명 | 식별자 + 점수 + 영향 제품 + 약점 분류 |
| 자동화 활용성 | 제한적 | 스캐너, ITSM, SBOM 연계에 적합 |
| 운영 가치 | 참조 기준 통일 | 우선순위와 영향 분석 보강 |
| 한계 | 세부 메타데이터 부족 | 환경별 실제 영향은 별도 검증 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CVE Record | 취약점 기본 식별과 설명을 제공함 |
| CVSS Metrics | 기술적 심각도와 벡터 정보를 제공함 |
| CPE Mapping | 영향받는 제품과 버전 식별에 활용함 |
| CWE and References | 약점 유형과 벤더 권고와 분석 자료를 연결함 |

```text
CVE 수집 -> NVD 메타데이터 보강 -> 자산/제품 매핑 -> 우선순위 산정 -> 패치/예외 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약점 확인 -> NVD 조회 -> CPE/CVSS 매핑 -> 내부 자산 대조 -> 조치 우선순위 결정 -> 재점검
```

1. **취약점 확인**: CVE ID를 기준으로 해당 취약점을 식별함
2. **NVD 조회**: CVSS와 CPE와 CWE와 참고 정보를 확인함
3. **내부 자산 대조**: 자산 목록과 SBOM과 제품 버전을 매핑함
4. **조치 결정**: 패치, 예외, 추가 검증 여부를 정함
5. **재점검**: 적용 후 동일 CPE와 CVE 노출이 해소됐는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 스캐너와 자산 관리 시스템을 연계하는 환경에서는 NVD의 CPE와 CVSS를 기본 입력으로 삼되 벤더 백포트와 제품 커스텀 버전을 별도 검증해야 하며 영향 자산 식별 정확도와 잘못된 패치 대상 비율 감소로 확인함
2. SBOM 기반 공급망 보안 운영에서는 NVD 데이터를 자동 수집해 라이브러리 노출을 빠르게 선별하되 분석 지연과 오매칭을 고려해 벤더 권고와 함께 확인하고 고위험 구성요소 탐지 시간과 재검증 완료율로 확인함

## Ⅶ. 결론

- NVD는 CVE를 실제 운영 데이터로 확장해 주는 기반 저장소이므로 자동화에 유용하지만 최종 조치 판단은 자산 맥락과 공급자 정보까지 함께 봐야 함
