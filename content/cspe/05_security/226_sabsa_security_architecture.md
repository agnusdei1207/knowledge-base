# 📖 【암기용】 개념 완전 이해

> 목적: SABSA를 처음 보는 사람도 업무 목표와 보안 아키텍처가 어떻게 연결되는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: SABSA는 업무 목표에서 보안 요구사항과 통제까지 추적하는 보안 아키텍처 방법론이다.
- **왜 필요한가**: 보안 장비를 많이 사도 업무 리스크와 연결되지 않으면 투자 우선순위가 흔들린다. SABSA는 "무엇을 보호할 것인가"를 업무 속성에서 출발해 설계 산출물로 이어 준다.
- **핵심 직관**: 경영진의 목표를 보안 설계 언어로 번역하는 계층형 설계 지도다.

## 깊이 이해
- **배경·문제의식**: 전통 보안 설계는 방화벽·IDS·암호화처럼 기술 목록부터 시작해 업무 가치, 규제, 리스크 소유자를 놓치기 쉽다. SABSA는 비즈니스 속성, 위협, 통제, 운영지표를 한 흐름으로 묶어 추적성을 확보한다.
- **작동 원리**: Zachman Framework처럼 관점과 추상화 계층을 나누되, 보안 목적에 맞춰 Contextual, Conceptual, Logical, Physical, Component, Operational 계층으로 전개한다. 각 계층은 Why, What, How, Who, Where, When 질문에 답한다.
- **비유**: 건물을 지을 때 임대 목적, 동선, 구조, 자재, 장비, 유지보수 계획을 따로 쓰지 않고 한 설계도 세트로 관리하는 방식과 같다.
- **구체 예시**: 인터넷뱅킹 업무에서 "부정송금 0.01% 이하" 목표를 세우면, 고객 인증, 거래위험평가, 이상거래탐지, 감사로그 보존 5년, RTO 30분 요구로 내려간다.
- **흔한 오해·주의점**: SABSA는 제품이나 인증제도가 아니다. TOGAF와 함께 쓰면 엔터프라이즈 아키텍처 안에 보안 관점을 넣고, Zero Trust와 함께 쓰면 신원·기기·세션 검증 통제를 구체화한다.

## 연결 개념
- TOGAF — 기업 아키텍처 거버넌스 틀, SABSA는 보안 관점 보완
- Zero Trust — 신뢰 가정 제거 원칙, SABSA의 Logical/Physical 통제로 구현
- 리스크 기반 보안 — 업무 영향도와 위협 가능성을 설계 우선순위로 변환

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SABSA는 계층 이름 암기가 아니라 업무목표-리스크-통제-지표의 추적성을 설계하는 아키텍처 답안으로 전개한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SABSA는 업무 목표에서 보안 속성, 통제, 운영지표까지 연결하는 business-driven security architecture 방법론이다.
> 2. **가치**: 경영 요구, 규제, 위협모델, 기술통제를 한 계층 모델로 묶어 보안투자 우선순위와 감사 근거를 만든다.
> 3. **판단 포인트**: TOGAF는 기업 아키텍처 틀, Zero Trust는 접근통제 원칙, SABSA는 보안 요구사항 추적성 확보 수단으로 구분한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 아키텍처 방법론 이해 확인 | Contextual/Conceptual/Logical/Physical/Component/Operational 6계층 | 계층명만 나열하고 업무 리스크 추적성을 누락 |
| 엔터프라이즈 보안 설계 역량 확인 | 업무속성 -> 보안서비스 -> 기술통제 -> 운영지표 연결 | 방화벽·암호화 제품 목록으로 축소 |
| TOGAF·Zero Trust 관계 판단 확인 | TOGAF 보완, Zero Trust 구현 통제 매핑 | 세 방법론을 경쟁 관계로 단정 |

> 요약: SABSA 문제는 보안통제를 업무목표와 리스크 근거로 설명하는 아키텍처 추적성 답안이 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 업무 목표 기반 보안아키텍처
- 배경: 보안 아키텍처를 제품·네트워크 구성부터 설계하면 업무 목표, 규제, 위협, 운영 지표의 추적성이 끊어짐
- 필요성: SABSA 6계층으로 업무속성·리스크·통제·지표를 연결하고 핵심 업무 100%, 통제 매핑 누락률 5% 이하 기준으로 감사 증적을 관리해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Business Goal -> Contextual -> Conceptual -> Logical
  / Physical -> Component -> Operational
  / Risk Attribute -> Control -> Metric
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|
| Contextual | 업무 목표·이해관계자·보호대상 식별 | 비즈니스 속성, 리스크 범위 |
| Conceptual | 보안 원칙·서비스 모델 수립 | 인증, 인가, 감사, 가용성 원칙 |
| Logical | 논리 보안 서비스와 도메인 설계 | IAM, 네트워크 존, 데이터 분류 |
| Physical | 플랫폼·제품·기술 배치 | FW, WAF, SIEM, KMS, PAM |
| Operational | 운영 절차와 지표 관리 | SLA, RTO/RPO, 감사로그, KPI |

> 요약: SABSA는 업무 요구를 6계층 산출물로 낮추며, 각 산출물은 리스크와 통제 근거를 갖는다.

---

## Ⅲ. 동작원리 및 흐름도

```text
업무 목표 식별 -> 보안 속성 도출 -> 리스크 분석
  -> 보안 서비스 설계 -> 기술 통제 배치
  -> 운영지표 측정 -> 잔여 리스크 승인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 프로세스, 자산, 이해관계자 식별 | 자산등급 4단계, 소유자 100% 지정 |
| 2 | 기밀성·무결성·가용성·책임추적성 속성 도출 | 규제 조항, 업무 영향도 매핑 |
| 3 | 위협·취약점·영향도 기반 리스크 산정 | 위험등급 High/Medium/Low |
| 4 | 보안서비스와 기술통제 배치 | IAM, 암호화, SIEM, PAM 통제 매핑 |
| 5 | 운영지표 측정과 개선 | MTTR, 감사로그 누락률, 정책위반 건수 |

> 요약: SABSA는 리스크 산정 후 통제를 배치하고 운영지표로 잔여 리스크를 재평가하는 폐루프 구조다.

## Ⅳ. 특징

| 구분 | 기존 기술중심 설계 | SABSA | 수치·판단 기준 |
|:---|:---|:---|:---|
| 출발점 | 제품, 네트워크 구간 | 업무 목표, 보안 속성 | 업무 프로세스 커버리지 100% |
| 추적성 | 정책-장비 연결 약함 | 목표-리스크-통제-지표 연결 | 통제 매핑 누락률 5% 이하 |
| 적용 범위 | 프로젝트 단위 | 기업 아키텍처·감사·운영 | 핵심 시스템 20개 이상 조직 |
| 관계 모델 | 단독 보안 설계 | TOGAF 보완, Zero Trust 구현 | EA 원칙, ZTNA/IAM 연계 |

> 요약: SABSA는 보안 제품 배치가 아니라 업무 속성에서 운영지표까지 추적 가능한 설계 기준을 제공한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | SABSA | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | TOGAF 중심 EA | EA 안에 보안 관점 삽입 | 전사 아키텍처와 보안 거버넌스 통합 시 |
| 접근통제 | Zero Trust 원칙 | ZT 통제를 업무 리스크에 매핑 | 원격·클라우드 접근 비중 50% 이상 |
| 운영/위험 | 체크리스트 감사 | 통제-지표-잔여리스크 관리 | 감사 지적 반복 2회 이상 |

> 요약: SABSA는 TOGAF와 Zero Trust를 대체하지 않고, 보안 요구와 구현 통제의 연결 기준으로 사용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문서 과다 | 계층 산출물 중복 | 핵심 업무 10개부터 적용 | 산출물 승인 리드타임 |
| 추적성 단절 | 업무속성-통제 매핑 누락 | 요구사항 ID, 통제 ID, 로그 ID 연결 | 매핑 누락률 5% 이하 |
| 운영 미흡 | 설계 후 KPI 미측정 | SIEM·GRC 대시보드 연동 | 월간 리스크 리뷰 1회 |

> 요약: SABSA 도입 리스크는 방법론 복잡도이며, 산출물 범위와 추적성 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 업무 커버리지 | 핵심 업무 100%, 일반 업무 80% | 업무-자산-통제 매트릭스 |
| 통제 효과 | High 리스크 90% 이상 통제 매핑 | 리스크 레지스터, GRC |
| 운영 검증 | 감사로그 누락률 1% 이하, MTTR 30분 | SIEM, SOAR, 월간 점검표 |

> 요약: 성공 여부는 문서 수가 아니라 업무 커버리지, 통제 매핑률, 운영지표 달성률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 핵심 업무 10개를 선정해 Contextual/Conceptual 계층에서 업무속성, 규제, 자산등급, 리스크 소유자를 100% 지정한다.
2. Logical/Physical 계층에서 IAM, KMS, WAF, SIEM, PAM 통제를 요구사항 ID와 1:N으로 매핑한다.
3. Operational 계층에서 MTTR 30분, 감사로그 누락률 1% 이하, High 리스크 조치기한 30일 지표를 운영회의에 반영한다.

**결론 (2줄):**
- 기술사 판단: 전사 보안 거버넌스와 감사 추적성이 필요하면 SABSA를 기준으로 삼고, 단일 시스템 보안설계는 위협모델링+통제목록으로 축소한다.
- 향후 방향: SABSA 산출물은 Zero Trust, 클라우드 보안태세관리, GRC 자동화와 연결되어 리스크 기반 보안 운영으로 발전한다.
