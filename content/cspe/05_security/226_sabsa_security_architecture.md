## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 비즈니스 요구사항으로부터 출발하여 보안 아키텍처를 하향식(Top-Down)으로 도출하고, 6개 계층과 6개 관점(5W1H)의 매트릭스로 설계부터 운영까지의 양방향 추적성을 보장하는 엔터프라이즈 보안 아키텍처 프레임워크입니다.
- **필요성**: 보안이 비즈니스 목표와 괴리된 채 '단순한 기술적 방어막(예: 방화벽 도입)'으로 전락하는 것을 막고, 경영진에게 보안 투자의 정당성(ROI)을 논리적으로 입증하기 위해 필수적입니다.
- **핵심 직관**: **"보안을 위한 6x6 육하원칙 설계도"** - 사장님(비즈니스)부터 실무자(엔지니어)까지 "왜(Why) 이 방화벽(What)이 필요한지" 묻는다면, 경영 목표에서부터 물리적 장비 룰셋까지 막힘없이 이어지는 번역기 역할을 합니다.

## 2. 깊이 이해하기 (In-Depth Comprehension)
- **배경**: 1990년대 IT 아키텍처의 표준이 된 자크만 프레임워크(Zachman Framework)의 6x6 매트릭스 개념을 정보보안 영역에 특화시켜 존 셔우드(John Sherwood)가 고안했습니다.
- **작동 원리 (6x6 매트릭스)**:
  - **수평 계층 (6 Layers)**: 상황적(Contextual, L1) $\rightarrow$ 개념적(Conceptual, L2) $\rightarrow$ 논리적(Logical, L3) $\rightarrow$ 물리적(Physical, L4) $\rightarrow$ 컴포넌트(Component, L5) $\rightarrow$ 운영적(Operational, L6)
  - **수직 관점 (5W1H)**: 무엇(What/자산), 왜(Why/동기), 어떻게(How/프로세스), 누가(Who/사람), 어디서(Where/네트워크), 언제(When/시간)
- **비유**: 건물을 지을 때, 건축주(경영진)가 요구하는 "안전하고 넓은 로비(L1)"라는 요구사항이, 건축가(설계자)의 도면(L3)을 거쳐, 시공업자(구현자)의 "방탄유리 두께 5cm(L5)"로 구체화되는 과정과 완벽히 일치합니다.
- **구체 예시**: 클라우드 전환 시 "글로벌 규제 준수(L1)"라는 비즈니스 목표는 "제로 트러스트 원칙(L2)"을 거쳐 "VPC 분리 및 암호화(L3, L4)"를 지나 "AWS KMS 고객 관리형 키(CMK) 적용(L5)"으로 구체화되며, 모든 과정이 단절 없이 연결됩니다.
- **흔한 오해/주의점**: 36개 칸을 모두 빈틈없이 채워야 한다는 강박은 "문서화의 늪"을 만듭니다. SABSA는 철학이자 프레임워크일 뿐, 조직의 규모와 프로젝트 성격에 맞게 필수 칸만 선택(Tailoring)하여 가볍게 적용하는 것이 핵심입니다.

## 3. 연결 개념 (Related Concepts)
- **Zachman Framework**: SABSA의 뼈대가 된 전사적 아키텍처(EA) 프레임워크.
- **TOGAF**: 구조를 제시하는 SABSA와 결합하여, 실질적인 아키텍처 개발 프로세스(ADM)를 제공.
- **DevSecOps**: SABSA의 컴포넌트(L5) 및 운영(L6) 계층을 IaC 기반으로 자동화하여 민첩하게 구현하는 최신 파이프라인 보안.

# ✍️ 답안용 골격 (Exam Preparation)

### Ⅰ. 핵심 인사이트
- **본질**: 기술 중심의 파편화된 보안을 극복하고, 비즈니스 목표(Risk & ROI)에서 출발하여 보안 통제를 도출하는 하향식(Top-Down) 36-Cell 엔터프라이즈 보안 아키텍처 프레임워크.
- **가치**: 경영진의 언어(리스크)와 엔지니어의 언어(코드/장비) 간의 '의미적 단절(Semantic Gap)'을 해소하여, 보안 투자의 양방향 추적성(Two-way Traceability)을 완벽히 보장함.
- **판단 포인트**: SABSA 단독 도입보다는, TOGAF(아키텍처 프로세스)나 ITIL(운영 관리)과 같은 기존 EA 프레임워크와 결합(Tailoring)하여 전사적 IT 거버넌스 내에 보안을 내재화(Security by Design)하는 전략이 필수적임.

### Ⅱ. SABSA의 핵심 구조 (6x6 매트릭스)
```text
┌─────────────────────────────────────────────────────────────┐
│                   [ SABSA 6x6 Matrix ]                      │
├───────┬──────┬──────┬──────┬──────┬──────┬──────────────────┤
│ 관점  │ What │ Why  │ How  │ Who  │ Where│ When (5W1H)      │
├───────┼──────┼──────┼──────┼──────┼──────┼──────────────────┤
│ L1    │ 비즈니스 자산과 리스크 (Contextual / 경영진)      │
│ L2    │ 보안 정책 및 프레임워크 (Conceptual / 아키텍트)   │
│ L3    │ 논리적 보안 서비스/정보 흐름 (Logical / 설계자)   │
│ L4    │ 물리적 보안 메커니즘/배치 (Physical / 엔지니어)   │
│ L5    │ 구체적 보안 솔루션/설정 (Component / 구현자)      │
│ L6    │ 보안 관제 및 운영 관리 (Operational / 운영자)     │
└───────┴─────────────────────────────────────────────────────┘
```

### Ⅲ. 양방향 추적성 (Two-way Traceability) 메커니즘
1. **하향식 도출 (Top-Down, Justification)**
   - 비즈니스 요구사항(L1) $\rightarrow$ 보안 정책(L2) $\rightarrow$ 논리 아키텍처(L3) $\rightarrow$ 물리 장비(L4) $\rightarrow$ 설정 적용(L5)
   - "목표 달성을 위해 어떤 통제가 필요한가?" (보안의 당위성 부여)
2. **상향식 검증 (Bottom-Up, Verification)**
   - 보안 솔루션(L5) $\rightarrow$ 물리 설계(L4) $\rightarrow$ 보안 기능(L3) $\rightarrow$ 전략적 기여(L2) $\rightarrow$ 리스크 완화(L1)
   - "이 방화벽 예산이 회사의 어떤 위험을 줄이는가?" (투자 ROI 입증)

### Ⅳ. SABSA 라이프사이클 (선순환 구조)
1. **Strategy & Planning**: 비즈니스 목표 식별 및 리스크 프로파일링 (L1, L2).
2. **Design**: 아키텍처 매트릭스를 통한 논리/물리/컴포넌트 설계 (L3, L4, L5).
3. **Implement**: 벤더 솔루션 도입, IaC 배포 및 아키텍처 인스턴스화.
4. **Manage & Measure (피드백)**: 운영(L6) 데이터 기반 핵심위험지표(KRI) 측정 및 전략(L1) 재조정.

### Ⅴ. 타 프레임워크와의 융합 전략
- **SABSA + Zachman**: 자크만의 전사적 뷰에 SABSA의 보안 렌즈를 플러그인(Plug-in)하여 통합 EA 구축.
- **SABSA + TOGAF**: SABSA의 정적인 36-Cell 구조물을 TOGAF ADM(Architecture Development Method)의 동적 프로세스로 구현.
- **SABSA + ISO 27001**: ISO 27001의 보안 통제(Control) 항목을 SABSA 매트릭스 각 셀의 검증 지표로 활용.

### Ⅵ. 결론 및 실무적 판단 포인트
- CISO는 클라우드 네이티브 환경에서 "단품 솔루션 도입"의 유혹을 버리고, SABSA 기반의 거버넌스를 확립해야 합니다.
- L2(개념적 계층)에 '제로 트러스트(ZTA)' 원칙을 확고히 세팅하면, 향후 L5(컴포넌트 계층)의 기술 스택(VPN $\rightarrow$ SASE)이 급변하더라도 전체 아키텍처의 비즈니스 정합성과 보안성은 흔들림 없이 유지될 수 있습니다.

### 💡 문제 유형별 목차 전환 포인트
- **[전사적 보안 거버넌스 및 IT 연계 문제]**: Ⅰ과 Ⅲ(양방향 추적성)을 전면에 배치하여, 비즈니스와 보안의 '의미적 단절'을 해결하는 프레임워크로서의 가치를 강조.
- **[클라우드 환경 보안 아키텍처 설계 문제]**: Ⅱ(매트릭스)와 Ⅵ(실무 적용)을 강조하여, L1의 '유연성/글로벌 컴플라이언스' 요구가 어떻게 L5의 'CSP 네이티브 보안 서비스(AWS WAF, KMS)'로 매핑되는지 구체적 시나리오 제시.
