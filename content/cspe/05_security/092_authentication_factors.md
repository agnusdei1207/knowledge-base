## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 사용자 신원을 확인하기 위한 세 가지 인증 요소로, 지식(Knowledge)·소유(Possession)·생체(Inherence) 기반으로 분류됨 |
| **배경/필요성** | 단일 패스워드 인증은 피싱·크래킹에 취약하며, 다중 요소 조합으로 인증 강도를 높여야 함 |
| **출제 의도** | 3대 인증 요소의 특성과 MFA 조합 설계 원칙을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 지식기반  | --> | 소유기반  | --> | 생체기반  |
| (What I  |     | (What I  |     | (What I  |
|  Know)   |     |  Have)   |     |  Am)     |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 지식 기반 | 비밀번호·PIN·보안 질문 등 사용자만 아는 정보로 인증함 | 금고 비밀번호 |
| 소유 기반 | OTP 토큰·스마트카드·휴대폰 등 사용자만 가진 물리적 장치로 인증함 | 집 열쇠 |
| 생체 기반 | 지문·얼굴·홍채·음성 등 신체 고유 특성으로 인증함 | 본인의 얼굴 |

> 요약: 지식(아는 것)·소유(가진 것)·생체(자신인 것)의 3요소를 조합하여 인증 강도를 결정함.

## Ⅲ. 절차
```
+------------+     +------------+
| 1차인증    | --> | 2차인증    |
| (지식:PW)  |     | (소유:OTP) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 접근허가   | <-- | 3차인증   |
|            |     | (생체:지문)|
+------------+     +------------+
```

1. 1차 인증: 사용자가 ID/패스워드(지식 요소)를 입력하여 기본 신원을 확인함
2. 2차 인증: OTP·인증 앱 푸시(소유 요소)로 추가 검증을 수행함
3. 3차 인증: 고위험 거래 시 지문·얼굴 인식(생체 요소)으로 최종 확인함
4. 접근 허가: 요구된 인증 레벨을 모두 충족한 경우에만 리소스 접근을 허용함

> 요약: 지식 → 소유 → 생체 순으로 인증 요소를 추가하여 단계적으로 신뢰를 확보함.

## Ⅳ. 문제점
- 패스워드 재사용: 사용자가 여러 서비스에 동일 패스워드를 사용하여 크레덴셜 스터핑에 노출됨
- 소유 장치 분실: OTP 토큰·휴대폰 분실 시 인증 불가 및 복구 절차가 복잡함
- 생체 정보 유출: 생체 데이터는 변경이 불가능하여 유출 시 영구적 피해가 발생함

## Ⅴ. 개선방안
- (단기) 패스워드 관리자 권장: 서비스별 고유 패스워드를 생성·관리하여 재사용을 방지함
- (중기) FIDO2 패스키 전환: 공개키 기반 인증으로 패스워드 자체를 제거함
- (장기) 행위 기반 연속 인증: 키스트로크·마우스 패턴 등 행위 생체를 지속 분석하여 세션 중 탈취를 탐지함

## Ⅵ. 전망
- FIDO2 패스키 보급으로 패스워드 없는 인증이 확산되며, 행위 기반 연속 인증이 제로 트러스트 환경의 핵심 인증 체계로 발전할 전망임
