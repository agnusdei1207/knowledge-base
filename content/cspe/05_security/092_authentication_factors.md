# 📖 【암기용】 개념 완전 이해

> 목적: 인증 요소를 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 사용자가 본인임을 증명하는 근거를 지식, 소유, 생체 특성으로 나누는 인증 분류
- **왜 필요한가**: 비밀번호 하나만 쓰면 피싱, 재사용, 유출 DB 대입 공격에 취약하다. 서로 다른 요소를 조합해야 한 요소가 탈취되어도 계정 접근을 막을 수 있다.
- **핵심 직관**: "아는 것", "가진 것", "몸에 있는 것"은 공격자가 훔쳐야 하는 대상이 서로 다르다.

## 깊이 이해
- **배경·문제의식**: 인증은 단순 로그인 화면이 아니라 신원 보증의 근거를 설계하는 일이다. 지식 요소는 재사용·피싱 위험, 소유 요소는 단말·키 분실 위험, 생체 요소는 변경 불가 특성이 있어 생체 원본 대신 template hash·secure enclave 저장이 필요하다.
- **작동 원리**: 사용자는 password/PIN 같은 지식 요소, OTP 앱·보안키·스마트카드 같은 소유 요소, 지문·얼굴 같은 생체 요소 중 하나 이상을 제시한다. 서버는 요소 독립성, 재사용 가능성, 피싱 저항성, 복구 절차를 함께 평가한다.
- **비유**: 금고를 열 때 비밀번호, 실물 열쇠, 지문을 각각 요구하는 방식이다. 비밀번호가 유출되어도 열쇠와 지문이 없으면 열 수 없다.
- **구체 예시**: 관리자 로그인은 password 12자 이상, FIDO2 보안키, 생체 기반 user verification을 조합하고, SMS OTP는 SIM swap 위험 때문에 고위험 계정의 주 인증 요소로 제한한다.
- **흔한 오해·주의점**: 비밀번호와 보안질문은 둘 다 지식 요소라서 다중 요소가 아니다. 같은 유형을 두 번 요구하면 2단계 인증일 수는 있어도 MFA 독립성 요건은 약하다.

## 연결 개념
- MFA - 서로 다른 인증 요소 조합
- FIDO2/WebAuthn - 공개키 기반 소유 요소와 피싱 저항성
- Risk-Based Authentication - 위험도에 따른 추가 인증

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 인증 요소 답안은 용어 나열이 아니라 요소 독립성, 피싱 저항성, 복구 위험, 재인증 기준을 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 인증 요소는 사용자가 본인임을 증명하는 근거를 knowledge, possession, inherence로 분류한 기준임
> 2. **가치**: 서로 독립된 요소를 조합하면 비밀번호 유출, 단말 분실, 생체 위조 등 단일 실패 지점을 분산함
> 3. **판단 포인트**: 같은 요소 중복은 MFA가 아니며, 피싱 저항성은 FIDO2 같은 origin-bound possession에서 확보됨

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인증 요소 분류 이해 확인 | 지식, 소유, 생체와 대표 기술 | OTP와 비밀번호를 모두 지식 요소처럼 혼동 |
| 독립성 판단 확인 | 서로 다른 공격 경로와 복구 절차 | 비밀번호+보안질문을 MFA로 서술 |
| 보안·운영 설계 확인 | 피싱 저항성, 분실 복구, 재인증 기준 | 생체 원본 저장 또는 복구 절차 누락 |

> 요약: 이 문제는 인증 수단 이름보다 요소 독립성과 실패 시 복구 위험을 판단하는 능력을 본다.

## Ⅰ. 개요 및 필요성

- 개요: 신원 증명 근거 분류
- 배경: 지식 요소 단독 인증은 비밀번호 유출, 재사용, 피싱 프록시 공격에 노출된다.
- 필요성: NIST SP 800-63B 기준으로 지식·소유·생체 요소를 독립 조합해 계정 탈취 성공 조건을 늘려야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User -> Knowledge / Possession / Inherence -> Verifier -> Session/Token
       / Password, PIN
       / OTP, FIDO2 Key, Smart Card
       / Fingerprint, Face
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 지식 요소 | 사용자가 아는 값 확인 | password, PIN, 보안질문 |
| 소유 요소 | 사용자가 가진 장치 확인 | OTP app, FIDO2 key, 스마트카드 |
| 생체 요소 | 사용자 신체 특성 확인 | 지문, 얼굴, 홍채, local template |
| 검증자 | 요소 값을 검증하고 세션 발급 | IdP, PAM, WebAuthn RP |

> 요약: 인증 요소는 지식·소유·생체의 근거를 검증자에게 제시해 세션 또는 토큰으로 전환하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그인 요청 -> 1차 요소 검증 -> 위험도 평가
-> 추가 요소 선택 -> 독립성 확인 -> 세션 발급 -> 실패 로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 계정 식별과 1차 요소 검증 | password hash, PIN retry limit |
| 2 | 위험도 평가 | 신규 단말, 위치, IP reputation, impossible travel |
| 3 | 추가 요소 요구 | OTP, FIDO2, biometric user verification |
| 4 | 독립성 확인 | knowledge+possession, possession+inherence 조합 |
| 5 | 세션·로그 처리 | session rotation, 401 로그, 재인증 조건 |

> 요약: 인증은 요소 검증 후 위험도에 따라 추가 요소를 요구하고, 독립 조합이 성립할 때 상위 authn strength를 부여한다.

---

## Ⅳ. 특징

| 구분 | 기존/단일 요소 | 인증 요소 설계 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 지식 | password 단독 | Argon2id/bcrypt, 12자 이상, breached password 차단 | 실패 5회 잠금, 재사용 금지 |
| 소유 | SMS OTP 의존 | TOTP, Push, FIDO2 key | TOTP 30초, FIDO2 origin binding |
| 생체 | 서버 원본 저장 | 단말 내 template, liveness detection | 원본 이미지 저장 금지 |
| 독립성 | 같은 요소 반복 | knowledge+possession 등 조합 | 비밀번호+보안질문 제외 |

> 요약: 인증 요소 설계의 핵심은 요소 종류가 다르고 공격자가 훔쳐야 하는 대상이 분리되는지이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 신원 보증 | password 단독 | 요소별 신뢰 수준 분리 | 관리자, 결제, 개인정보 접근 |
| 피싱 저항성 | OTP 코드 입력 | FIDO2/WebAuthn origin binding | 원격 피싱 위험 계정 |
| 복구 절차 | 고객센터 수동 초기화 | recovery code, verified device, 2인 승인 | 계정 탈취 후 복구 우회 방지 |

> 요약: 고위험 업무는 지식 요소보다 피싱 저항성이 있는 소유 요소와 복구 통제를 우선 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 피싱 | password, OTP 코드 탈취 | FIDO2, number matching, origin check | 피싱 신고 대비 성공 로그인 비율 |
| SIM swap | SMS OTP 번호 탈취 | TOTP/FIDO2 전환, 통신사 변경 후 재인증 | 전화번호 변경 후 24시간 고위험 표시 |
| 생체 오남용 | 원본 저장, 위조 시도 | 단말 내 template, liveness, fallback 제한 | biometric 실패율, fallback 사용률 |

> 요약: 요소별 리스크는 피싱, SIM swap, 생체 원본 관리이며 대체 요소와 복구 절차까지 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 요소 독립성 | 관리자 계정 MFA 100%, 같은 요소 중복 0건 | IAM policy audit |
| 피싱 저항성 | 고위험 계정 FIDO2 등록률 95% 이상 | IdP enrollment report |
| 재인증 | 권한 변경·결제·단말 등록 시 step-up 100% | access log, SIEM rule |

> 요약: 인증 요소 운영은 등록률, 독립성, 재인증 적용률로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 요소 정책: 일반 사용자는 password+TOTP, 관리자와 개발자는 FIDO2 보안키 2개 등록, password는 Argon2id/bcrypt와 유출 목록 차단 적용
2. 위험 기반 재인증: 신규 단말, 권한 변경, 결제, 개인정보 다운로드 시 possession 요소 또는 FIDO2 user verification 요구
3. 복구 통제: recovery code 10개 이하 일회용 발급, 전화번호 변경 후 24시간 고위험 표시, 관리자 복구는 2인 승인과 감사로그 저장

**결론 (2줄):**
- 기술사 판단: 일반 계정은 knowledge+possession, 관리자와 고위험 API는 phishing-resistant possession을 기본 요소로 선택해야 함
- 향후 방향: 인증 요소는 비밀번호 중심에서 FIDO2 기반 공개키 소유 요소와 위험 기반 재인증으로 이동함
