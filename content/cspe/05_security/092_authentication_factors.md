## 미리 알고가기

- 인증 요소는 사용자가 아는 것, 가진 것, 자신인 것처럼 서로 다른 근거로 신원을 확인하는 기준임
- 지식 요소는 비밀번호나 PIN, 소유 요소는 OTP 기기나 휴대폰, 생체 요소는 지문이나 얼굴처럼 이해하면 됨
- 같은 종류를 두 번 쓰는 것은 강도를 높일 수 있어도 엄밀한 다중 요소 인증과는 다름

## Ⅰ. 개요

- **정의/개념**: 인증 방식은 지식, 소유, 생체 요소로 나뉘며 시스템은 이를 조합해 사용자 신원과 인증 수준을 결정함
- **배경/필요성**: 단일 비밀번호만으로는 피싱, 재사용, 탈취를 막기 어려움. 서비스 중요도에 맞는 강한 인증 근거가 필요함

## Ⅱ. 특징

- 지식 요소는 익숙하고 배포가 쉽지만 재사용과 피싱에 취약함
- 소유 요소는 기기나 앱 기반 증명으로 강도를 높이지만 분실과 복구 절차가 필요함
- 생체 요소는 편의성이 높지만 유출 시 변경이 어렵고 기기 보호가 중요함
- 인증 설계는 요소 수보다 독립성과 피싱 저항성을 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 지식 기반 | 소유 기반 | 생체 기반 |
|:---|:---|:---|:---|
| 대표 예시 | 비밀번호, PIN | OTP 앱, 보안키, 스마트폰 | 지문, 얼굴, 홍채 |
| 장점 | 도입이 쉬움 | 강도 향상과 분리 가능 | 편의성과 사용자 경험이 좋음 |
| 주요 위험 | 피싱, 재사용, 추측 | 분실, 탈취, 푸시 피로 | 오인식, 프라이버시, 변경 어려움 |
| 적합 환경 | 일반 로그인 기본 요소 | 중요 시스템 추가 인증 | 기기 잠금 해제, 강한 사용자 확인 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 식별 | 누가 로그인하려는지 계정을 지정함 |
| 인증 요소 선택 | 서비스 위험도에 맞는 요소를 요구함 |
| 검증 수단 | 비밀번호 검증, OTP 확인, 생체 확인을 수행함 |
| 복구와 예외 | 분실과 오인식 상황의 복구 절차를 마련함 |

```text
계정 식별 -> 필요한 인증 요소 결정 -> 요소별 검증 -> 접근 허용 -> 복구/예외 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 위험도 분류 -> 인증 요소 설계 -> 로그인 시 검증 -> 실패/복구 처리 -> 주기 재평가
```

1. **위험도 분류**: 어떤 서비스에 어느 수준 인증이 필요한지 정함
2. **요소 설계**: 지식과 소유와 생체 중 적합한 조합을 선택함
3. **로그인 검증**: 각 요소를 순차 또는 동적으로 확인함
4. **실패와 복구 처리**: 분실과 잠금과 오인식에 대응함
5. **재평가**: 공격 동향과 사용자 경험을 반영해 조정함

## Ⅵ. 실무 적용 및 유의점

1. 일반 사용자 서비스는 중요 기능과 계정 변경 화면부터 소유 요소를 더하고 계정 탈취 감소·복구 절차 남용 여부로 확인함
2. 내부 업무 시스템은 요소 독립성을 유지하고 동일 요소 중복 사용 제거·고위험 업무 추가 인증 적용 여부로 확인함

## Ⅶ. 결론

- 인증 요소 설계는 서로 다른 근거를 독립적으로 결합할수록 실제 보안 강도가 높아짐
