## Ⅰ. 개요
- 정의: 보안 관제 시 발생하는 수많은 경보(Alert)에 대해 조사, 분석, 차단 등의 대응 절차를 인력의 개입 없이 자동화된 워크플로우로 엮어놓은 지침서(코드 형태)임.
- 배경/필요성: 폭증하는 보안 경보(Alert Fatigue)로 인해 관제 인력의 피로도 극대화, 단순 반복 작업 최소화, 침해 발생 시 대응 시간(MTTR) 획기적 단축 필요.
- 출제 의도: 차세대 보안 관제(SOAR)의 핵심 기술인 플레이북의 구성 요소(트리거, 액션, 연동)와 이를 통한 보안 운영 최적화 개념을 평가함.

## Ⅱ. 구성요소
+-------------------+       +-------------------+       +-------------------+
|  트리거 (Trigger) | ----> |  액션/조건 (Logic)| ----> | API 연동 (Integr.)|
| (경보/이벤트 발생)|       | (자동 분석 및 판단)|       | (방화벽 차단 등)  |
+-------------------+       +-------------------+       +-------------------+

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 트리거 (Trigger) | 플레이북을 시작하게 만드는 방아쇠 (SIEM에서 1차 탐지된 피싱 경보 등) | 화재 경보기 작동 |
| 조건과 액션 (Logic & Action) | IP 평판 조회, 악성코드 샌드박스 전송 등 플레이북 내부에 정의된 순서도 기반 자동 수행 절차 | 소방 매뉴얼에 따른 펌프 및 스프링클러 가동 |
| API 연동 플러그인 (Integration)| 이기종 보안 장비(방화벽 차단, 백신 검사)나 IT 시스템(슬랙 알림, 티켓 생성)과 연동하는 통로 | 외부 소방서 통신 연결 및 출동 요청 |

> 요약: 경보(트리거)가 울리면 정해진 로직(액션)에 따라 여러 이기종 보안 장비들(API 연동)을 지휘하여 자동으로 위협을 차단함.

## Ⅲ. 절차
+-------------------+   +-------------------+   +-------------------+   +-------------------+
| 1. 이벤트 수신    |-->| 2. 정보 자동 보강 |-->| 3. 조건 판단/조치 |-->| 4. 티켓팅/종료    |
+-------------------+   +-------------------+   +-------------------+   +-------------------+

1. 이벤트 수신(Trigger): SIEM 플랫폼 등에서 '악성 메일 수신' 또는 '랜섬웨어 감염 징후' 등 특정 이벤트 경보 발생
2. 정보 자동 보강(Enrichment): 외부 위협 인텔리전스(CTI) 피드에 해당 IP/URL 조회를 자동 요청하여 평판 및 악성 여부 데이터 추가
3. 조건 판단/조치(Action): 수집된 데이터가 임계치(예: 악성 확률 90% 이상)를 넘으면 방화벽/EDR에 API로 IP 차단 또는 호스트 격리 명령 수행
4. 티켓팅/종료: 조치 완료 후 ITSM 서비스 등에 작업 이력(티켓)을 자동 생성하고 보안 담당자 메신저(Slack 등)로 최종 결과만 알림

> 요약: 알람이 울리면 자동으로 악성 여부를 조사하고 확인되면 즉각 차단한 뒤 담당자에게 결과만 보고함.

## Ⅳ. 문제점
- 이기종 장비 연동 한계: 다양한 보안 솔루션이 각기 다른 규격의 API를 사용하여 호환성 문제가 발생하며, 솔루션 패치 시 API 규격이 바뀌어 플레이북 고장 발생
- 예외 상황(False Positive) 대처 미흡: 플레이북 로직이 잘못 짜여 정상적인 사내 대규모 시스템 트래픽을 디도스로 오인해 자동 차단할 경우 전사 업무 마비 초래
- 플레이북 관리의 파편화: 공격 기법이 변할 때마다 새로운 플레이북을 무분별하게 찍어내어, 수백 개의 스크립트 중 어떤 것이 최신인지 형상 관리가 안 됨
- 보안 인력의 기술 종속화: 신입 관제 인력이 플레이북이 자동으로 처리해 주는 결과만 보다 보니 수동으로 패킷을 뜯고 딥다이브 분석하는 기본기 상실

## Ⅴ. 개선방안
- 단기: 100% 완전 자동 차단보다는, '분석 정보 수집'까지만 플레이북이 수행하고 최종 '차단 액션' 버튼은 숙련된 분석가가 승인하는 반자동(Human-in-the-loop) 적용
- 중기: MITRE ATT&CK 프레임워크와 플레이북을 매핑하여 특정 전술/기법(TTPs) 방어에 빈틈이 없는지 가시화하고 체계적 형상 관리 수행
- 장기: AI 및 LLM을 플레이북 엔진에 탑재하여, 정해진 스크립트 기반(Rule-based)을 넘어 변화하는 공격 상황에 맞춰 동적으로 액션을 제안하는 AI-Driven SOAR 구축

## Ⅵ. 전망
- 인력난에 시달리는 보안 관제센터(SOC)의 유일한 해답인 SOAR 및 플레이북 자동화는 이제 선택이 아닌 필수로 모든 중견 이상 기업에 확산될 것임.
- 자연어로 "피싱 대응 워크플로우 짜줘"라고 입력하면 생성형 AI가 즉석에서 코드를 생성하여 API를 붙여주는 'No-Code/Generative Playbook' 시대로 빠르게 진화할 전망임.
