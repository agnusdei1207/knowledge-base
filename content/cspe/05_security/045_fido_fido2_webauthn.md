## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 매번 아이디와 비밀번호를 타이핑하는 대신, 스마트폰의 '지문 인식', '얼굴 인식(FaceID)', 혹은 'USB 보안 키'를 터치하는 것만으로 전 세계 모든 웹사이트에 빠르고 강력하게 로그인하는 **차세대 비밀번호 없는(Passwordless) 글로벌 인증 표준 기술**입니다.
- **필요성**: 해커가 피싱 사이트로 유도해서 비밀번호를 훔쳐 가거나(스미싱), 다른 사이트에서 털린 아이디/비밀번호로 넷플릭스 등에 마구잡이로 대입하는(Credential Stuffing) 해킹 사고의 80% 이상이 '비밀번호'라는 낡은 시스템 때문에 일어납니다. 비밀번호 자체를 아예 없애버려야 합니다.
- **핵심 직관**: **"지문을 보내는 게 아니라, 자물쇠와 열쇠를 나눠 갖기"**. 
  - 과거: 내 비밀번호 '1234'를 서버에 통째로 보관합니다. 서버가 털리면 다 털립니다.
  - FIDO: 내 지문을 서버로 '절대' 보내지 않습니다. 지문은 오직 내 스마트폰(철통 금고) 안에서만 확인용으로 쓰입니다. 내 폰에서 나만의 '고유 자물쇠(공개키)'와 '열쇠(개인키)'를 만듭니다. 서버에는 껍데기 '자물쇠'만 던져두고, 내가 로그인할 때 폰에 지문을 대면 폰 안에 숨겨둔 '열쇠'로 찰칵! 하고 도장(전자서명)을 찍어서 보냅니다. 서버는 비밀번호를 보관하지 않아 털릴 게 없습니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 삼성전자, 애플, 구글, MS 등 글로벌 빅테크들이 "더 이상 패스워드의 끔찍한 해킹과 불편함을 못 견디겠다"며 동맹(FIDO Alliance)을 맺어 만들었습니다. 모바일용(FIDO 1.0)을 거쳐, 이제는 웹 브라우저와 PC 환경 전체를 통합한 **FIDO2(WebAuthn)** 로 진화했습니다.
- **가치**: 가장 근본적인 해킹(피싱, 무차별 대입 공격)을 **물리적/수학적으로 원천 차단**하면서도, 사용자에게는 '손가락만 대면 로그인 끝'이라는 압도적인 UX(편의성)를 제공하는 보안계의 궁극적 종착역입니다.

## 3. 어떻게 작동하는가? (Mechanism)
FIDO 인증은 **비대칭키 암호화(공개키/개인키)** 구조를 활용하여 두 단계로 작동합니다.

1. **가입 (Registration) - 자물쇠와 열쇠 세팅**
   - 사용자가 네이버에서 "FIDO 지문 로그인 사용"을 클릭합니다.
   - 내 폰(Authenticator, 인증 장치)이 안전한 금고 구역(TEE 등)에서 1쌍의 공개키와 개인키를 만들어 냅니다.
   - **(핵심!)** 개인키(내 열쇠)는 내 폰의 철통 금고 깊숙이 박혀서 평생 밖으로 나오지 않습니다. 공개키(껍데기 자물쇠)만 네이버 서버로 던져서 등록합니다.

2. **인증 (Authentication) - 로그인 시도**
   - 내가 네이버에 로그인 시도 시, 네이버 서버가 무작위 수학 문제(Challenge 난수)를 폰으로 보냅니다.
   - 폰에 "지문을 대세요" 창이 뜨고, 내가 지문을 찍으면 $\rightarrow$ 지문이 일치하므로 폰 금고가 열리고 개인키가 작동합니다.
   - 폰이 그 개인키로 네이버의 수학 문제에 도장(전자서명)을 꽉 찍어서 돌려보냅니다.
   - 네이버 서버는 예전에 받아둔 껍데기 공개키로 그 도장이 진짜인지 확인 후 문을 열어줍니다 (로그인 성공!).

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례**: 
  - **은행 앱 간편 로그인**: 토스나 카카오뱅크에서 지문 1초 컷으로 로그인하는 것이 100% FIDO 기술입니다.
  - **웹 브라우저 (WebAuthn)**: 스마트폰 앱을 넘어, PC에서 크롬(Chrome) 브라우저로 깃허브나 구글 계정 로그인 시, 맥북의 Touch ID를 스캔하거나 YubiKey(USB 하드웨어 보안 키)를 꽂아 터치하는 것이 바로 FIDO2 표준입니다.
  - **패스키 (Passkey)**: 폰을 잃어버리면 FIDO 키가 다 날아가서 난감했던 약점을 보완한 최신 기술. 내 FIDO 열쇠가 구글 클라우드나 애플 iCloud 1password 등에 동기화되어 폰을 바꿔도 지문 로그인이 유지됩니다.

## 5. 핵심 비교 및 연결 개념 (Relation)
- **기존 생체인증 vs FIDO**: 
  - 과거: 내 지문 사진(데이터)을 서버로 전송해서 비교함 (서버 해킹 시 내 지문 영구 유출 대참사).
  - FIDO: 지문은 오직 '스마트폰 칩 속의 금고(개인키) 문을 여는 물리적 스위치'로만 쓰임. 지문 데이터가 폰 밖으로 1비트도 안 나감. 서버는 지문이 어떻게 생겼는지 모름.

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 서버에 비밀번호나 생체 정보를 전송/보관하지 않고, 단말기 로컬 환경(TEE 등)에서 생성된 비대칭키(PKI) 쌍을 이용하여 피싱과 크레덴셜 스터핑 공격을 원천 차단하는 Passwordless(무암호) 글로벌 인증 표준 아키텍처.
- **가치**: 보안을 높이면 편의성이 떨어진다는 기존 보안의 트레이드오프(Trade-off) 공식을 깨고, **보안성(PKI 전자서명)과 사용자 편의성(1초 생체인증)** 을 동시에 극대화한 현대 인증 생태계의 패러다임 시프트.
- **판단 포인트**: FIDO1.0(모바일 앱 종속성)의 한계를 넘어, FIDO2는 **WebAuthn(W3C 웹 표준 API)** 과 **CTAP(장치 간 통신 프로토콜)** 을 결합하여 브라우저와 PC OS(Windows Hello) 환경까지 기기 종속성 없이 통합(Ubiquitous)된 인증 아키텍처를 완성함.

### Ⅱ. FIDO 아키텍처의 3대 핵심 분리 원칙
보안과 프라이버시를 유지하기 위한 설계 철학.
1. **서버와 단말의 분리**: 생체 인식(Matching)은 100% 모바일 단말기(Client) 내부의 안전한 영역(Secure Enclave, TrustZone)에서만 수행됨. 생체 원본 템플릿 정보는 절대 네트워크를 타지 않음.
2. **도메인(Origin) 분리**: 각 웹사이트(Relying Party)마다 완전히 새롭고 독립적인 공개키-개인키 쌍을 각각 생성함. A 사이트에서 생성된 키로 B 사이트를 인증할 수 없어 사이트 간 교차 추적(Tracking) 완벽 차단.
3. **피싱 방어 (Phishing-Resistant)**: 브라우저가 서버에서 보낸 도메인과 현재 사용자가 떠 있는 실제 도메인 주소(Origin URL)를 검증하므로, 해커가 만든 가짜 네이버(피싱 사이트)에서는 아예 개인키가 작동(서명)하지 않음. 피싱의 수학적 종말.

### Ⅲ. FIDO2 / WebAuthn 아키텍처 및 메커니즘
FIDO2는 모바일 앱 외부의 웹 브라우저(PC) 확장을 위한 2개의 핵심 프로토콜로 구성됨.
1. **WebAuthn (Web Authentication API)**: 
   - 웹 서버(Relying Party)와 브라우저 간의 표준 자바스크립트 API 통신 규약. 서버가 Challenge(난수)를 브라우저에 던지는 체계.
2. **CTAP (Client to Authenticator Protocol)**:
   - 브라우저(또는 OS)가 외부 인증 장치(USB YubiKey, Bluetooth 스마트폰 스캔, NFC 키 등)와 통신하여 서명을 요청하고 값을 받아오는 하드웨어 통신 규약.

**동작 메커니즘 (Authentication Flow)**:
1. 웹 서버(RP)가 난수 기반의 `Challenge` 생성 후 브라우저(WebAuthn)로 전송.
2. 브라우저가 CTAP를 통해 로컬 인증기(Authenticator, 지문센서 등) 호출.
3. 사용자 로컬 생체 인증 성공 시 $\rightarrow$ 인증기 내부의 **개인키(Private Key)** 언락(Unlock).
4. 언락된 개인키로 `Challenge` 값과 `Origin(도메인)` 정보에 **전자 서명(Signature)** 수행.
5. 서명된 값을 서버로 응답 $\rightarrow$ 서버는 사전에 보관된 사용자의 **공개키(Public Key)** 로 서명 유효성 검증 후 세션 인가.

### Ⅳ. 최신 진화 동향: 패스키 (Passkeys)
- **FIDO의 한계**: 초기 FIDO 인증키(개인키)는 폰 내부의 하드웨어 칩셋(TPM)에 갇혀(Device-bound) 있어, 기기를 분실하면 수십 개 사이트의 FIDO 등록이 다 날아가서 비밀번호 복구 프로세스를 다시 밟아야 하는 치명적 UX 붕괴 발생.
- **패스키 (Multi-Device FIDO Credentials)**: 
  - FIDO 개인키가 기기에 종속되지 않고, Apple iCloud Keychain이나 Google Password Manager 등 클라우드(OS 생태계)를 통해 안전하게 **동기화(Sync)** 됨.
  - 새 아이폰을 사도 기존 폰에 있던 FIDO 개인키가 클라우드를 타고 자동으로 넘어와 즉각 지문 로그인(Passkey)이 가능해지는 획기적 개선. (현재 글로벌 빅테크 전면 적용 중).

### Ⅴ. 결론 및 실무적 판단 포인트
- 차세대 B2C/B2B 웹 서비스 아키텍처 설계 시, 비밀번호 초기화 비용(CS 운영비)과 크레덴셜 탈취 리스크(계정 보상 비용)를 극적으로 낮추기 위해 회원가입 폼(Form)에서 패스워드 필드 자체를 아예 걷어내고 **FIDO2(WebAuthn) 기반 패스키(Passkey)를 1차 인증 수단(Primary Auth)** 으로 전면 도입하는 것이 글로벌 아키텍처 권고 표준입니다.

### 💡 문제 유형별 목차 전환 포인트
- **[Passwordless 인증 및 FIDO 1.0 vs FIDO 2.0 발전]**: Ⅰ과 Ⅲ번 항목을 집중 전개하여, 기존 서버에 비밀번호나 생체값을 던지는 구형 방식의 붕괴(해킹 위험)를 꼬집고, 로컬 기기 내 PKI 비대칭키 쌍에 기반한 혁신적 도메인 분리 아키텍처를 상세 도식화.
- **[WebAuthn 프로토콜 동작 원리 및 Phishing 방어 기작]**: Ⅲ번 WebAuthn의 동작 메커니즘(Challenge-Response)과 Ⅱ번의 도메인(Origin) 검증 방식을 엮어, 왜 피싱 메일 사이트에 접속해도 FIDO가 해커의 인증 요청을 기술적으로 튕겨내는지 서술.
