## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 동일한 키를 사용하여 데이터를 암호화 및 복호화하는 암호화 기법임 |
| **배경/필요성** | 대용량 데이터의 기밀성을 고속으로 보장하기 위한 효율적인 암호화 메커니즘 필요 |
| **출제 의도** | 블록 암호와 스트림 암호의 차이점, 안전성(AES) 및 성능 특성 이해도 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|    Plaintext      |      |   Secret Key      |      |    Ciphertext     |
|   (평문 데이터)   +----->|  (비밀키 적용)    +----->|  (암호화된 문장)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **평문/암호문** | 보호할 원본 데이터(평문)와 알고리즘에 의해 변환된 데이터(암호문)임 | 금고에 넣기 전/후의 문서 |
| **비밀키** | 암호화와 복호화에 공통으로 사용되는 동일한 키 값임 | 자물쇠와 동일한 열쇠 |
| **암호 알고리즘** | 키를 이용해 평문을 암호문으로 변환하는 수학적 규칙(AES 등)임 | 자물쇠의 내부 기계 장치 |

> 요약: 하나의 비밀키로 암호화/복호화를 수행하여 고속 처리가 가능한 데이터 보호 체계임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
|  1. 키 분배    |-->| 2. 데이터 암호 |-->|  3. 암호문 전송|-->| 4. 데이터 복호 |
| (안전한 채널)  |   | (송신자 수행)  |   | (네트워크 이용)|   | (수신자 수행)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **키 분배**: 송수신자 간에 안전한 채널을 통해 비밀키를 사전 공유함
2. **데이터 암호화**: 송신자가 비밀키와 대칭 암호 알고리즘을 이용해 평문을 암호화함
3. **암호문 전송**: 암호화된 데이터를 네트워크를 통해 수신자에게 전송함
4. **데이터 복호화**: 수신자가 사전에 공유된 동일한 비밀키로 암호문을 평문으로 복호화함

> 요약: 안전한 키 분배 후, 단일 키를 통한 암/복호화로 고속 기밀성 보장 과정을 수행함.

## Ⅳ. 문제점
* **키 분배(Key Distribution)의 어려움**: 물리적/논리적으로 안전하게 키를 전달하기가 매우 어려움
* **키 관리 복잡성(N*(N-1)/2)**: 사용자가 늘어남에 따라 관리할 키의 수가 기하급수적으로 증가함
* **부인 방지 불가**: 동일한 키를 양측이 보유하여 작성자를 특정할 수 없음

## Ⅴ. 개선방안
* **단기 방안 (키 교환 도입)**: Diffie-Hellman 등 안전한 키 교환 프로토콜로 키 공유 문제 해결
* **중기 방안 (중앙 관리)**: KMS 구축을 통해 키 생성, 갱신, 폐기를 체계적으로 통제
* **장기 방안 (비대칭 결합)**: 비대칭 암호와 결합한 하이브리드 시스템 도입으로 부인 방지 동시 확보

## Ⅵ. 전망
* 양자 컴퓨터 시대에 대비하여 키 길이(AES-256 권장)를 확장해 안전성을 지속 강화할 전망임
* 하드웨어 가속(AES-NI) 및 경량 암호(IoT)와의 융합 기술이 필수적으로 요구됨
