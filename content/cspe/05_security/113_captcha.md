## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 사람과 봇을 구별하기 위한 자동화된 튜링 테스트로, 이미지·행위 분석 등 기계 판독이 어려운 과제를 제시하여 봇 접근을 차단하는 기술임 |
| **배경/필요성** | 자동화된 봇에 의한 계정 생성·크레덴셜 스터핑·스팸 공격이 증가하며, 사람만 통과 가능한 검증이 필요함 |
| **출제 의도** | CAPTCHA 유형별 원리와 reCAPTCHA v3의 리스크 스코어 기반 방식을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 챌린지   | --> | 응답검증  | --> | 리스크   |
| (과제)   |     | (서버)   |     | 스코어   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 챌린지 | 이미지 선택·텍스트 인식·행위 분석 등 봇이 풀기 어려운 과제를 제시함 | 입구 퀴즈 |
| 응답 검증 | 사용자 응답을 서버에서 검증하여 사람/봇을 판별함 | 퀴즈 정답 확인 |
| 리스크 스코어 | reCAPTCHA v3에서 사용자 행위를 분석하여 0.0~1.0 점수로 봇 가능성을 산출함 | 수상 행동 점수 |

> 요약: 챌린지 제시 → 응답 검증 → 리스크 스코어 산출로 사람과 봇을 구별함.

## Ⅲ. 절차
```
+------------+     +------------+
| 페이지로드  | --> | 행위분석   |
| (JS삽입)   |     | (마우스등) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 접근허가   | <-- | 서버검증  |
| 또는차단   |     | 스코어반환 |
+------------+     +------------+
```

1. JS 삽입: 웹 페이지에 reCAPTCHA JavaScript를 삽입하여 사용자 행위 수집을 시작함
2. 행위 분석: 마우스 움직임·스크롤·키 입력 패턴 등을 백그라운드에서 분석함
3. 서버 검증: 수집된 토큰을 서버가 Google reCAPTCHA API에 전송하여 리스크 스코어를 수신함
4. 접근 결정: 스코어가 임계치 이상이면 허가, 미만이면 추가 챌린지 또는 차단을 적용함

> 요약: JS 삽입 → 행위 분석 → 서버 검증 → 접근 결정으로 사용자 마찰 없이 봇을 탐지함.

## Ⅳ. 문제점
- 접근성 저해: 시각장애인·고령자가 이미지 CAPTCHA를 풀기 어려워 서비스 접근이 제한됨
- AI 우회: OCR·이미지 인식 AI의 발전으로 전통적 CAPTCHA의 봇 차단 효과가 감소함
- 프라이버시 우려: reCAPTCHA v3가 사용자 행위 데이터를 Google에 전송하여 프라이버시 이슈가 발생함

## Ⅴ. 개선방안
- (단기) 접근성 대안 제공: 음성 CAPTCHA·인증 코드 등 대체 수단을 함께 제공함
- (중기) 자체 호스팅 방식: hCaptcha·Turnstile 등 프라이버시 중심 대안으로 전환함
- (장기) 패스키 연동: FIDO2 인증으로 봇 구별과 인증을 동시에 해결하여 CAPTCHA 자체를 제거함

## Ⅵ. 전망
- Cloudflare Turnstile 등 프라이버시 보존형 봇 탐지가 확산되며, 장기적으로 패스키 기반 인증이 CAPTCHA를 대체할 전망임
