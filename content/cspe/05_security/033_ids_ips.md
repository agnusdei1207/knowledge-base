## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 
  - **IDS (Intrusion Detection System)**: 네트워크 트래픽이나 서버의 상태를 분석해 "해킹 공격이 발생했다!"고 경고만 울리는 탐지(CCTV) 시스템.
  - **IPS (Intrusion Prevention System)**: 탐지를 넘어, 공격 패킷을 능동적으로 즉각 끊어버리는(Drop) 차단(무장 경비원) 시스템.
- **필요성**: 방화벽은 "네이버(IP)에서 왔고 80포트(Web)를 쓰니 정상"이라며 통과시켜 버립니다. 하지만 그 정상적인 허용 문을 통해 바이러스나 제로데이 공격이 숨어 들어오는 것을 잡아내기 위한 '내용물 엑스레이 검사기'가 필요합니다.
- **핵심 직관**: **"보안 검색대의 엑스레이 판독관"**. 
  방화벽이 탑승객의 티켓(출발지, 도착지)만 검사한다면, IDS/IPS는 짐가방(Packet Payload)을 투시하여 그 안에 칼이나 마약(알려진 악성코드 패턴)이 들어있는지, 혹은 생수병이 규정(프로토콜)과 다르게 비정상적으로 큰지 샅샅이 뒤져냅니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 90년대 중반 해킹 기법이 고도화되자 시스템 내부의 로그를 뒤져 공격을 찾는 호스트 기반 IDS(HIDS)가 등장했고, 이후 네트워크 패킷 전체를 떠서 분석하는 네트워크 기반 IDS(NIDS)로 발전했습니다. 나중에는 경고만으로는 피해를 막기 늦다며 즉각 차단하는 IPS로 진화했습니다.
- **가치**: 심층 방어(Defense in Depth)의 두 번째 관문입니다. 방화벽의 맹점(허용된 포트를 통한 페이로드 공격)을 완벽히 메우고, 알려진 취약점(CVE)에 대한 웜바이러스 등의 전파를 원천적으로 차단합니다.

## 3. 어떻게 작동하는가? (Mechanism)

**1. 감시하는 위치 (어디서 볼 것인가?)**
- **NIDS / NIPS (네트워크 기반)**: 
  - 건물의 중앙 CCTV실. 네트워크 스위치 장비의 길목(Mirror 포트 또는 In-line)에 1대 설치하여, 지나다니는 '모든 패킷'을 도청하듯 가로채서 분석합니다.
  - 장점: 장비 1대로 수백 대의 서버를 한 번에 보호 가능, 서버에 부하 안 줌.
- **HIDS / HIPS (호스트 기반)**: 
  - 각 방마다 설치된 사설 블랙박스. 웹 서버나 DB 서버 내부에 백신처럼 '소프트웨어(Agent)'로 깔려서, 서버의 시스템 로그나 파일 변조 여부, 메모리 접근을 감시합니다.
  - 장점: 네트워크에서 암호화(HTTPS)되어 엑스레이로 못 본 공격도, 서버에서 복호화된 순간 잡아낼 수 있음.

**2. 잡는 방법 (어떻게 판단할 것인가?)**
- **시그니처 기반 (지식 기반, 오용 탐지)**: 
  - "이런 패턴의 패킷은 공격이다"라는 지명수배 전단지(DB)를 들고 비교합니다. 정확도가 높지만 전단지에 없는 '신종 공격(Zero-day)'은 통과시킵니다.
- **행위/이상 기반 (비정상 탐지)**: 
  - "우리 회사 직원은 보통 밤에 접속 안 하고, 10초에 1번 클릭하는데... 저놈은 새벽 2시에 1초에 100번 클릭하네?" 정상적인 패턴을 기계학습시켜두고, 이 기준(Baseline)에서 벗어나면 차단합니다. 신종 공격을 잡을 수 있지만 멀쩡한 직원을 차단(오탐)할 확률이 높습니다.

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례**: 
  - 대표적인 오픈소스 NIDS/NIPS 엔진으로 **Snort(스노트)** 와 **Suricata(수리카타)** 가 전 세계적으로 쓰이고 있습니다.
  - IPS 룰 예시 (Snort): `drop tcp any any -> 192.168.1.1 80 (msg:"SQL Injection Attack"; content:"UNION SELECT";)`
- **주의점 및 흔한 오해**: 
  - IDS는 트래픽의 복사본(Mirroring)만 받아서 구경하므로 통신 지연(Latency)을 일으키지 않습니다. 반면 IPS는 자기가 검사해서 통과 도장을 찍어주지 않으면 트래픽이 못 지나가는 **인라인(In-line)** 구조라, 장비가 고장나면 회사 인터넷 전체가 끊길(Single Point of Failure) 위험이 있습니다 (반드시 Bypass 모듈 설치 필요).

## 5. 핵심 비교 및 연결 개념 (Relation)
- **방화벽 vs IDS/IPS**: 
  - 방화벽 = L3/L4 관문 (IP/Port 기반 차단)
  - IDS/IPS = L4~L7 관문 (패킷 페이로드 속 악성 시그니처 분석)
- **연결 개념**: 현재 대부분의 독립형 IPS 장비는 시장에서 사장되었고, 차세대 방화벽(NGFW) 내부의 통합 엔진 기능(UTM) 중 하나로 흡수되어 동작하고 있습니다.

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 네트워크 트래픽(NIDS) 또는 운영체제 이벤트(HIDS)를 심층 패킷 검사(DPI) 및 이상 행위 분석을 통해 악의적 침해 시도를 탐지(Detection)하거나 실시간으로 차단(Prevention)하는 심층 보안 솔루션.
- **가치**: 포트 기반 방화벽(L3/L4)을 우회하여 허용된 채널(e.g., HTTP/80)로 유입되는 악성코드, 버퍼 오버플로우, 취약점 익스플로잇(Exploit)을 L7 애플리케이션 계층 수준에서 핀포인트로 방어함.
- **판단 포인트**: IPS 인라인(In-line) 배치 시 발생 가능한 SPOF(단일 장애점) 및 Latency 오버헤드를 해소하기 위한 Fail-Open(Bypass) 아키텍처 설계와, 오탐(False Positive)을 최소화하기 위한 지속적인 시그니처 튜닝 역량이 운영의 성패를 가름.

### Ⅱ. IDS와 IPS의 아키텍처 비교 및 전개 방식
**1. IDS (탐지 중심, Out-of-Band)**
- **동작 방식**: 네트워크 스위치의 미러링 포트(SPAN 포트)나 별도의 탭(TAP) 장비를 통해 원본 트래픽의 '복사본'을 전달받아 수동적으로 분석함.
- **장점**: 장비 장애나 트래픽 과부하 시에도 원본 비즈니스 트래픽(통신)에는 아무런 영향을 주지 않음(제로 레이턴시).
- **단점**: 탐지 후 TCP RST(Reset) 패킷을 보내 연결을 끊으려 시도하지만, 그사이 이미 악성 패킷 하나가 서버에 도달해 버리는 슬라이딩 윈도우 한계 발생 (사후 약방문).

**2. IPS (차단 중심, In-Line)**
- **동작 방식**: 트래픽이 반드시 IPS 장비의 인터페이스를 거쳐 가도록 직렬(In-line)로 배치됨. IPS 엔진이 패킷을 뜯어보고 '통과'를 승인해야만 밖으로 나갈 수 있음.
- **장점**: 단 하나의 악성 패킷도 서버에 닿기 전에 원천적으로 드랍(Drop) 가능. (선제 방어).
- **단점**: 
  - 병목 현상(Bottle-neck) 유발 가능성.
  - 장비 전원이 나가거나 엔진이 뻗으면 전체 네트워크 단절. $\rightarrow$ 방어책: 장애 발생 시 단순히 선을 이어주는 물리적 **Fail-Open (Bypass/Hardware Watchdog)** 기능 필수 구현.

### Ⅲ. 수집원에 따른 분류 (NIDS vs HIDS)
| 구분 | NIDS / NIPS (네트워크 기반) | HIDS / HIPS (호스트 기반) |
|---|---|---|
| **설치 위치** | 네트워크 길목 (스위치/라우터 하단) | 개별 서버 / PC 내부 (Agent 형태) |
| **분석 대상** | 전체 네트워크 패킷 (Pcap) | OS 시스템 로그, 파일 무결성, 프로세스/레지스트리 변경 |
| **장점** | 도입이 쉽고, 단일 장비로 넓은 커버리지 확보.<br>해커의 망 침입(Scanning) 초기 단계 탐지 용이. | **암호화 트래픽(HTTPS) 분석 가능** (서버 복호화 후).<br>네트워크 덤프가 아닌 실제 서버 내 변조(성공 여부) 확인 가능. |
| **단점** | 트래픽 암호화 시 페이로드(내용) 분석 불가.<br>네트워크 부하 시 패킷 유실(Drop) 위험. | 모든 서버마다 에이전트를 설치/업데이트해야 하는 관리 부하.<br>해커가 Root 권한 탈취 시 HIDS 자체를 끄거나 무력화 가능. |

### Ⅳ. 탐지 방법론 (Detection Methodology)
**1. 오용 탐지 (Misuse Detection / Signature-based)**
- 원리: 알려진 공격 패턴(시그니처) DB와 패킷의 페이로드를 매칭. (예: 바이러스 백신 패턴 매칭).
- 특징: 오탐(False Positive)이 매우 낮아 확실한 공격만 차단함. 그러나 패턴 DB에 없는 신규 제로데이(Zero-day) 공격은 절대 막지 못함(미탐/False Negative 발생).

**2. 이상 탐지 (Anomaly Detection / Behavior-based)**
- 원리: 기계학습/AI를 통해 네트워크의 '정상(Normal)' 트래픽 상태 프로파일링(Baseline) 구축. 임계치나 통계적 허용 범위를 벗어나는 행위를 공격으로 간주.
- 특징: 신종 제로데이 공격 및 변종 악성코드 탐지 가능. 그러나 정상적인 트래픽 폭증(이벤트 기간, 패치 배포 등)을 공격으로 착각해 오탐율이 매우 높음. 

*(현대의 IPS는 시그니처 엔진을 메인으로 구동하고 휴리스틱/AI 엔진을 보조로 결합한 하이브리드 탐지 모델 사용)*

### Ⅴ. 결론 및 실무적 판단 포인트
- **아키텍처 통합**: 스탠드얼론(Stand-alone) 전용 IPS 장비를 도입하는 시대는 지났으며, 트래픽을 두 번 뜯어보는 비효율(방화벽 복호화 $\rightarrow$ 검사 $\rightarrow$ IPS 복호화 $\rightarrow$ 검사)을 제거하기 위해 **NGFW 내부의 통합 IPS 룰셋** 활성화 및 CPU 하드웨어 가속(FPGA) 아키텍처를 선택하는 것이 표준입니다.
- **암호화 가시성**: 통신의 90%가 TLS 1.3으로 암호화되는 현재, NIPS 장비 자체만으로는 눈먼 장님에 불과합니다. 반드시 앞단에 **SSL 가시성 장비(SSL Decryption Forward Proxy)** 를 인라인으로 배치해 복호화된 평문 트래픽을 IPS로 던져주는 구성이 전제되어야 합니다.

### 💡 문제 유형별 목차 전환 포인트
- **[IDS/IPS 비교 및 설계 아키텍처 묻는 유형]**: Ⅱ번을 전면에 내세우고, In-line 배치에 따른 장애 대비(Fail-Open 설계)와 Out-of-Band 미러링의 지연 시간 차이를 도식화하여 실무적 장단점 서술.
- **[탐지 방법론(오용 vs 이상) 비교]**: Ⅳ번 항목을 메인으로 끌어올려, 오탐(False Positive)과 미탐(False Negative)의 트레이드오프 관계를 통계적 관점(Type I/Type II Error)으로 심화 전개.
