# 📖 【암기용】 개념 완전 이해

> 목적: 연합 학습을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 원천 데이터를 중앙으로 모으지 않고 각 기관·단말에서 학습한 모델 업데이트만 집계하는 분산 학습 방식
- **왜 필요한가**: 의료·금융·공공 데이터는 개인정보보호법, 계약, 영업비밀 때문에 원천 데이터를 공유하기 어렵다. 연합 학습은 데이터 이동을 줄이고 공동 모델 학습을 가능하게 한다.
- **핵심 직관**: 시험지를 한곳으로 걷지 않고, 각 학교가 채점한 오답 경향만 모아 공통 교재를 개선하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 전통적 AI는 데이터를 중앙 저장소에 모아 학습한다. 이 방식은 유출 피해 범위, 국외 이전, 동의 목적 초과, 기관 간 데이터 제공 문제를 만든다. 연합 학습은 데이터가 있는 위치에서 학습하고 서버는 모델 파라미터·그래디언트 업데이트만 받는다.
- **작동 원리**: 중앙 서버가 초기 모델을 배포하고, 참여 노드는 로컬 데이터로 학습한 뒤 업데이트를 보낸다. 서버는 FedAvg 등으로 업데이트를 집계해 글로벌 모델을 만들고 다시 배포한다. 차등프라이버시, 보안 집계, MPC, 동형암호를 결합해 업데이트 유출 위험을 줄인다.
- **비유**: 여러 병원이 환자 기록을 보내지 않고 각자 진단 모델을 개선한 후, 개선 방향만 중앙에서 평균 내 공통 모델을 갱신하는 구조다.
- **구체 예시**: 5개 병원이 CT 판독 모델을 학습할 때 원본 영상은 병원 밖으로 나가지 않고, 라운드당 모델 업데이트만 전송한다. 서버는 참여율, 정확도, AUC, 통신량, 멤버십 추론 공격 성공률로 결과를 평가한다.
- **흔한 오해·주의점**: 연합 학습은 데이터가 이동하지 않으므로 개인정보 문제가 사라진다는 뜻이 아니다. 모델 업데이트와 최종 모델에서도 재식별·멤버십 추론·모델 역전 공격이 가능하다.

## 연결 개념
- 차등프라이버시 - 업데이트와 결과 모델의 개인 기여도 노출 제한
- 보안 집계(Secure Aggregation) - 서버가 개별 업데이트를 직접 보지 못하게 함
- 모델 역전·멤버십 추론 - 연합 학습의 대표 프라이버시 공격

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 미이동 장점만 쓰지 말고, 업데이트·최종 모델에서 발생하는 프라이버시 공격과 방어 지표를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Federated Learning은 원천 데이터를 중앙 수집하지 않고 로컬 학습 결과를 집계해 글로벌 모델을 만드는 프라이버시 보존 AI 아키텍처이다.
> 2. **가치**: 의료·금융·제조 데이터 사일로 환경에서 데이터 제공 없이 공동 학습을 수행하고, 법적 근거·계약·동의 범위 문제를 완화한다.
> 3. **판단 포인트**: FedAvg, secure aggregation, differential privacy, non-IID 대응, 업데이트 공격 탐지를 함께 설계해야 실무 적용 가능하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프라이버시 보존 AI 구조 이해 확인 | 로컬 학습, 모델 업데이트, 중앙 집계, 글로벌 모델 | 데이터가 전혀 노출되지 않는다고 단정 |
| 보안 위협과 방어기술 판단 확인 | 멤버십 추론, 모델 역전, poisoning, DP, secure aggregation | 정확도 지표만 쓰고 공격 모델 누락 |
| 적용 조건 평가 확인 | non-IID, 통신량, 참여 노드 신뢰, 라운드 관리 | 중앙학습 대비 비용·운영 복잡도 미비교 |

> 요약: 이 문제는 연합 학습을 개인정보 보호 만능 기술이 아니라 공격면을 가진 분산 학습 구조로 이해하는지를 본다.

## Ⅰ. 개요 및 필요성

연합 학습은 데이터를 이동하지 않고 모델을 이동시키는 분산 학습 방식이다. 민감정보·영업비밀·국외 이전 규제로 중앙 데이터셋 구축이 어려운 의료·금융·공공 분야에서 필요하다. 다만 업데이트와 최종 모델이 개인정보 단서를 포함할 수 있어 PET 기반 보호조치가 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
Coordinator -> 초기 모델 배포 -> Client Local Training
            -> Model Update -> Secure Aggregation -> Global Model
            -> 평가/배포 -> 다음 라운드
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Coordinator | 라운드 관리, 모델 배포, 업데이트 집계 | 단일 장애점·신뢰 경계 |
| Client/Silo | 로컬 데이터 보관, 로컬 학습 수행 | 병원·은행·단말, non-IID 데이터 |
| Aggregator | FedAvg, 가중 평균, secure aggregation | 개별 업데이트 은닉 필요 |
| Privacy Layer | DP, MPC, 동형암호, 익명화 | 정확도·통신량·계산비용 트레이드오프 |

> 요약: 연합 학습은 코디네이터와 참여 노드가 모델 업데이트만 교환하고 개인정보 흐름은 로컬 경계 안에 묶는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
초기 모델 생성 -> 참여 노드 선택 -> 로컬 학습
-> 업데이트 암호화/노이즈 추가 -> 집계 -> 글로벌 모델 검증 -> 반복
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 초기 모델과 라운드 정책 배포 | 버전 해시, 참여 노드 목록 |
| 2 | 각 노드가 로컬 데이터로 학습 | local epoch, loss, 데이터 잔류 확인 |
| 3 | 업데이트 보호 후 중앙 집계 | secure aggregation, DP epsilon |
| 4 | 글로벌 모델 평가와 공격 테스트 | AUC, accuracy, membership inference rate |

> 요약: 연합 학습은 배포·로컬학습·보호된 집계·검증을 라운드 단위로 반복해 모델을 갱신한다.

---

## Ⅳ. 특징

| 구분 | 중앙집중 학습 | 연합 학습 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 데이터 이동 | 원천 데이터 중앙 수집 | 원천 데이터 로컬 보관 | 데이터 반출 0건 목표 |
| 프라이버시 위험 | 중앙 저장소 유출 | 업데이트·최종 모델 공격 | DP epsilon, 공격 성공률 |
| 학습 품질 | IID 대용량 데이터 확보 | non-IID·결측·참여율 영향 | AUC, F1, client drift |
| 운영 비용 | 데이터 파이프라인 중심 | 라운드·통신·노드 인증 중심 | 라운드당 MB, 실패 노드율 |

> 요약: 연합 학습은 데이터 이동을 줄이지만 업데이트 보호와 non-IID 품질 통제가 핵심 운영 과제이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 중앙 데이터 레이크 학습 | 로컬 학습 + 중앙 집계 | 데이터 반출 금지·기관 간 협력 |
| 비용/성능 | 학습 품질 높음, 유출 피해 집중 | 통신량·라운드 증가, 데이터 잔류 | AUC 감소 2%p 이내 허용 시 |
| 운영/위험 | 데이터 제공 계약 필요 | 참여 노드 인증·업데이트 검증 필요 | 노드 신뢰도, poisoning 탐지 |

> 요약: 데이터 반출이 법·계약상 제한되고 모델 품질 손실을 수치로 관리할 수 있을 때 연합 학습을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 모델 역전 | 업데이트·최종 모델에 훈련 정보 잔존 | DP, gradient clipping, red teaming | 재구성 공격 성공률 |
| 데이터 중독 | 악성 노드가 업데이트 조작 | robust aggregation, 노드 평판, 이상탐지 | 업데이트 이상치 비율 |
| 통신 병목 | 라운드 반복과 대형 모델 전송 | 압축, 클라이언트 샘플링, 비동기 학습 | 라운드당 전송량, 완료시간 |

> 요약: 실무 리스크는 프라이버시 공격, 중독 공격, 통신 병목이며 보호·검증·압축 기법을 함께 적용한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 모델 품질 | 중앙학습 대비 AUC 감소 2%p 이내 | 검증셋, 교차기관 테스트 |
| 프라이버시 | DP epsilon 문서화, 멤버십 추론 성공률 기준 이하 | 공격 시뮬레이션, NIST PET 평가 방식 |
| 운영 신뢰 | 노드 인증 100%, 업데이트 무결성 100% | mTLS, 서명 검증, 라운드 로그 |

> 요약: 도입 판단은 모델 품질, 프라이버시 공격 내성, 노드 신뢰 지표를 동시에 충족할 때 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 아키텍처: Coordinator, secure aggregator, client agent를 분리하고 mTLS와 업데이트 서명으로 참여 노드 인증 100% 적용
2. 프라이버시: gradient clipping, differential privacy, secure aggregation을 적용하고 epsilon·공격 성공률·재구성 품질을 실험 보고서에 기록
3. 운영: non-IID 데이터 분석, 라운드 실패 노드 재시도, poisoning 이상탐지, AUC/F1/전송량 대시보드를 라운드별 관리

**결론 (2줄):**
- 기술사 판단: 데이터 반출 금지와 기관 간 공동학습 요구가 동시에 있으면 연합 학습을 선택하되, 업데이트 공격 테스트를 필수 게이트로 둠
- 향후 방향: 차등프라이버시, MPC, 동형암호, confidential computing 결합으로 AI 학습의 데이터 최소 이동 구조가 확산됨
