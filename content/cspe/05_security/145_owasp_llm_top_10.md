## 미리 알고가기

- OWASP는 웹과 소프트웨어 보안 지침을 만드는 공개 보안 커뮤니티임
- 에이전트는 모델이 외부 도구를 호출해 실제 행동까지 이어 가는 구조임
- 임베딩은 문서 의미를 수치로 바꾼 표현이며 벡터 저장소는 이를 검색에 쓰는 저장소임
- OWASP LLM Top 10은 판에 따라 번호와 이름이 일부 바뀔 수 있으므로 버전 확인이 필요함

## Ⅰ. 개요

- **정의/개념**: OWASP LLM Top 10은 LLM 기반 애플리케이션을 설계, 개발, 운영할 때 우선 점검해야 할 대표 위험을 열 가지로 정리한 보안 기준표임
- **배경/필요성**: 기존 웹 보안 목록만으로는 프롬프트 조작, 모델 오염, 과도 권한, 비용 폭증처럼 생성형 AI 특유의 위험을 충분히 설명하기 어려워 별도 기준이 필요해짐

## Ⅱ. 특징

- 모델 자체보다 데이터, 프롬프트, 도구, 운영 통제를 함께 봄
- 설계 검토, 코드 리뷰, 레드팀 시험에 공통 언어를 제공함
- 위험을 외우는 목록이 아니라 아키텍처 점검 순서를 잡는 기준으로 쓰임
- 버전이 바뀌며 항목이 조정될 수 있어 현재 판과 연결된 통제도 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | OWASP Web Top 10 | OWASP LLM Top 10 |
|:---|:---|:---|
| 주된 입력면 | HTTP 요청, 세션, 서버 측 코드 | 프롬프트, 외부 문서, 모델 출력, 도구 호출 |
| 보호 자산 | 웹 애플리케이션과 데이터베이스 | 모델, 학습 데이터, 시스템 프롬프트, 추론 비용 |
| 자주 다루는 위험 | 인증, 권한, 인젝션, 구성 오류 | 프롬프트 인젝션, 민감정보 노출, 에이전트 권한, 무제한 소비 |
| 활용 방식 | 웹 서비스 안전 코딩 기준 | 생성형 AI 서비스 구조 점검 기준 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력·프롬프트 위험 | LLM01 프롬프트 인젝션, LLM07 시스템 프롬프트 유출, LLM08 벡터·임베딩 약점처럼 입력 경계를 다룸 |
| 데이터·모델 위험 | LLM02 민감정보 노출, LLM03 공급망, LLM04 데이터·모델 오염처럼 학습 자산과 모델 무결성을 다룸 |
| 실행·도구 위험 | LLM05 부적절한 출력 처리와 LLM06 과도한 에이전시처럼 출력과 외부 실행을 다룸 |
| 운영·가용성 위험 | LLM09 허위정보와 LLM10 무제한 소비처럼 서비스 신뢰와 비용 통제를 다룸 |

```text
자산 식별 -> Top 10 항목 매핑 -> 통제 설계 -> 시험·모니터링 -> 보완
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 범위 정의 -> 모델·데이터·도구 자산 식별 -> Top 10 위험 매핑 -> 우선순위 통제 설계 -> 레드팀과 운영 점검
```

1. **서비스 범위 정의**: 어떤 모델과 데이터와 도구를 쓰는지 정함
2. **자산 식별**: 프롬프트, 벡터 저장소, 모델 API, 외부 연동을 나열함
3. **위험 매핑**: 각 자산에 해당하는 Top 10 위험을 연결함
4. **통제 설계**: 권한, 필터, 검증, 비용 한도를 설계함
5. **시험·점검**: 레드팀과 운영 지표로 실제 취약 구간을 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 생성형 AI 서비스를 처음 설계할 때는 Top 10을 아키텍처 점검표로 써서 빠진 통제를 찾고 미해결 고위험 항목 수와 재현된 레드팀 공격 건수로 확인함
2. 에이전트와 검색 증강 생성이 붙은 서비스는 버전이 바뀔 때 항목 이름만 외우지 말고 현재 구조에 어떤 위험이 다시 생겼는지 재매핑해야 하며 분기별 재점검 누락 건수와 새로 추가된 통제 항목 반영률로 점검함

## Ⅶ. 결론

- OWASP LLM Top 10은 암기 목록이 아니라 생성형 AI 서비스의 위험을 빠짐없이 구조화하는 설계 기준표로 써야 함
