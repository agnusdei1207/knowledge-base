## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 임의의 길이를 가진 데이터를 고정된 길이의 고유한 해시값(다이제스트)으로 변환하는 단방향 함수임 |
| **배경/필요성** | 데이터의 무결성 검증과 원본 데이터를 복원할 수 없는 안전한 패스워드 저장 방식 필요 |
| **출제 의도** | 해시 함수의 주요 특성(단방향성, 충돌 회피성) 및 SHA 시리즈의 알고리즘 원리 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Input Data       |      |  Hash Function    |      |  Hash Value       |
| (가변 길이 원본)  +----->| (SHA-256 / SHA-3) +----->| (고정 길이 다이제스트)
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **입력 데이터(Message)** | 길이 제한 없이 해시 함수의 대상이 되는 원본 데이터임 | 사람의 고유한 신체 |
| **해시 함수(Hash Function)** | 입력값을 고정된 출력값으로 압축/변환하는 수학적 알고리즘임 | 지문 채취기 |
| **해시값(Digest)** | 해시 함수를 통해 생성된 고정된 크기의 고유 식별값임 | 개인의 고유한 지문 |

> 요약: 가변 데이터를 입력받아 역산이 불가능한 고정 길이의 고유 식별자(다이제스트)를 생성함.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 패딩 처리   |-->| 2. 블록 분할   |-->| 3. 압축 함수   |-->| 4. 해시값 생성 |
| (길이 맞춤)    |   | (일정 크기 나눔)|   | (연산 반복)    |   | (최종 다이제스트)
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **패딩 처리**: 원본 데이터의 길이가 블록 크기의 배수가 되도록 의미 없는 비트(패딩)를 추가함
2. **블록 분할**: 패딩된 전체 데이터를 처리하기 쉬운 고정된 크기의 데이터 블록으로 나눔
3. **압축 함수 적용**: 각 블록을 순차적으로 압축 함수에 통과시키며 이전 블록의 결과와 혼합(연산)함
4. **해시값 생성**: 모든 블록에 대한 반복 연산이 완료되면 최종적인 고정 길이 해시값을 도출함

> 요약: 패딩과 블록 분할 후 반복적인 연산을 거쳐 최종 단일 해시값을 추출하는 단계를 거침.

## Ⅳ. 문제점
* **충돌(Collision) 발생 가능성**: 비둘기집 원리에 의해 서로 다른 입력이 동일한 해시값을 갖는 충돌 발생 위험 상존
* **레인보우 테이블 공격**: 미리 계산된 해시값 테이블을 이용하여 원래 패스워드를 역추적하는 취약점 존재
* **해시 연산 속도 과다(무차별 대입)**: 해시 생성 속도가 너무 빠르면 오프라인 무차별 대입 공격에 악용될 수 있음

## Ⅴ. 개선방안
* **단기 방안 (강력한 알고리즘)**: MD5, SHA-1 등 취약한 알고리즘을 폐기하고 SHA-256 이상 도입
* **중기 방안 (솔트 추가 적용)**: 임의의 난수(Salt)를 패스워드와 결합하여 해싱함으로써 레인보우 테이블 공격 무력화
* **장기 방안 (키 스트레칭 적용)**: PBKDF2, bcrypt 등 해시를 수천 번 반복하는 기법으로 연산 속도를 늦춰 무차별 대입 공격 방어

## Ⅵ. 전망
* SHA-2의 구조적 약점 대안으로 스펀지 구조를 채택한 SHA-3의 도입이 블록체인 등에서 점진적으로 확대될 전망임
* 양자 컴퓨터 환경에서도 충돌 회피성을 유지하기 위해 더 긴 출력 길이를 갖는 해시 알고리즘 연구가 지속될 것임
