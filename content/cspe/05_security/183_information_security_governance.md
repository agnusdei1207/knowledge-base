## 미리 알고가기

- 거버넌스는 조직 목표에 맞게 의사결정, 책임, 감독 구조를 세우는 관리 체계임
- CISO는 정보보호 최고책임자로 보안 전략과 위험 관리 책임을 맡음
- 보안 지표는 투자와 통제 효과를 경영진이 판단할 수 있게 하는 측정값임

## Ⅰ. 개요

- **정의/개념**: 정보보호 거버넌스는 정보보호 목표와 책임과 의사결정 구조를 경영 목표와 연결해 보안 위험을 지속적으로 통제하는 관리 체계임
- **배경/필요성**: 보안이 기술 부서의 개별 조치에 머물면 투자 우선순위와 책임이 흐려짐. 경영진이 위험과 성과를 보고 결정할 구조가 필요함

## Ⅱ. 특징

- 보안 전략을 사업 목표와 규제 요구와 연결함
- 이사회, 경영진, CISO, 현업의 역할과 책임을 분명히 함
- 위험 기반으로 예산과 통제 우선순위를 결정함
- 감사와 지표를 통해 보안 활동이 실제로 작동하는지 감시함

## Ⅲ. 종류 및 비교

| 판단 기준 | 보안 운영 관리 | 정보보호 거버넌스 |
|:---|:---|:---|
| 초점 | 통제 실행과 사고 대응 | 방향 설정, 책임, 감독 |
| 의사결정 수준 | 보안 조직 내부 | 경영진과 이사회 포함 |
| 판단 기준 | 취약점, 이벤트, 운영 지표 | 사업 위험, 투자 효과, 규제 준수 |
| 산출물 | 운영 절차, 로그, 조치 내역 | 정책, 위원회 의사록, 위험 보고, KPI |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 경영진 책임 | 보안 목표와 위험 허용 수준을 승인하고 자원을 배정하는 상위 책임임 |
| 보안 조직과 역할 | CISO, 보안팀, 현업, 감사 조직의 권한과 책임을 나누는 구조임 |
| 정책과 표준 | 조직 전체가 따라야 할 보안 원칙과 기준을 공식화한 문서 체계임 |
| 위험관리 체계 | 자산과 위협과 취약점을 기준으로 우선순위와 처리 전략을 정하는 체계임 |
| 성과와 감사 | 보안 지표와 내부 감사로 통제 효과와 준수 상태를 확인하는 감독 장치임 |

```text
경영 목표 -> 보안 전략 -> 정책/역할 -> 위험관리 -> 성과 측정/감사
```

## Ⅴ. 원리 및 절차 흐름도

```text
목표 설정 -> 책임 배정 -> 정책 승인 -> 위험 보고 -> 투자 결정 -> 성과 점검
```

1. **목표 설정**: 조직의 사업 목표와 규제 요구를 보안 목표로 연결함
2. **책임 배정**: CISO와 현업과 감사 조직의 역할을 정함
3. **정책 승인**: 보안 정책과 표준과 예외 승인 기준을 공식화함
4. **위험 보고**: 주요 위험과 처리 현황을 경영진에게 보고함
5. **성과 점검**: KPI, 감사 결과, 사고 추세를 보고 개선을 지시함

## Ⅵ. 실무 적용 및 유의점

1. 보안 투자는 취약점 수보다 사업 영향과 잔여위험 기준으로 우선순위를 정하고 고위험 예외 승인 건수와 처리 지연 일수로 경영 책임을 확인함
2. CISO 조직은 운영 부서에 종속되면 이해상충이 생길 수 있으므로 보고 라인과 예외 승인 절차를 분리하고 감사 지적 재발률로 독립성을 점검함

## Ⅶ. 결론

- 정보보호 거버넌스는 보안 업무를 많이 하는 것이 아니라 보안 위험을 누가 어떤 기준으로 결정하고 책임질지 정하는 경영 체계임
