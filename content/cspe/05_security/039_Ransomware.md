## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 사용자 시스템의 핵심 데이터나 파일 시스템을 암호화하여 접근을 차단한 후, 복호화 키를 대가로 금전(가상화폐)을 요구하는 악성코드임 |
| **배경/필요성** | 기업의 단순 데이터 파괴를 넘어 이중/삼중 협박을 통한 막대한 금전적 피해가 발생하여 비즈니스 생존을 위협함 |
| **출제 의도** | 대칭/비대칭 암호가 악용되는 구조 이해, 백업(3-2-1 전략)의 중요성, RaaS(Ransomware as a Service) 생태계 파악 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
| Initial Access    |      | Crypto Engine     |      | Command & Control |
| (피싱/취약점 침투)+----->| (AES+RSA 하이브리드)+----->| (암호키 전송/협박)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **초기 침투 (Access)** | 사회공학적 스피어 피싱 메일, RDP 무차별 대입, 소프트웨어 취약점 등을 통해 시스템에 최초 잠입함 | 창문을 깨고 집에 숨어들어감 |
| **암호화 엔진 (Crypto)** | 피해자의 로컬 파일을 매우 빠른 AES(대칭키)로 암호화하고, 그 AES 키를 해커의 RSA(공개키)로 암호화함 | 집안 물건을 자물쇠로 잠그고 그 열쇠를 해커의 금고에 넣음 |
| **C&C 서버 (통제)** | 피해자 PC에서 생성된 암호키를 해커의 서버로 은밀히 빼돌린 후, 바탕화면에 협박장(Ransom Note)을 띄움 | 인질범의 지령 본부 |

> 요약: 최첨단 하이브리드 암호 기술을 악용해 파일을 잠그고, 익명성이 보장되는 가상화폐를 요구하는 범죄 비즈니스임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 침투 및 장악|-->| 2. 백업본 삭제 |-->| 3. 파일 암호화 |-->| 4. 협박(갈취)  |
| (피해망 내부탐색)|   | (복구 수단 차단)|   | (하이브리드 암호)|   | (비트코인 요구)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **침투 및 횡적 이동**: 내부망에 침투한 후 액티브 디렉터리(AD) 권한을 탈취하여 조직 전체 서버로 은밀하게 확산됨
2. **백업 무력화**: 볼륨 섀도 복사본(VSS) 삭제 및 사내 백업 서버를 먼저 파괴하여 자체 복구 가능성을 원천 차단함
3. **데이터 유출 및 암호화**: 주요 기밀 데이터를 외부로 먼저 빼돌린 후(이중 협박 용도), 로컬 파일들을 고속으로 암호화 처리함
4. **협박 및 결제 요구**: 바탕화면을 바꾸고, 암호화된 파일의 복호화 프로그램 대가로 다크웹을 통한 암호화폐 송금을 강요함

> 요약: 내부망을 완전히 장악해 자체 복구를 불가능하게 만든 후, 데이터를 인질로 삼아 조직의 숨통을 조이는 과정임.

## Ⅳ. 문제점
* **이중/삼중 협박(Double Extortion)**: 단순히 파일을 암호화하는 것에 그치지 않고, 훔쳐낸 기밀 데이터를 외부에 공개하겠다고 협박하거나 디도스 공격을 병행함
* **RaaS의 등장을 통한 공격 대중화**: 해킹 기술이 없는 일반인도 다크웹에서 랜섬웨어 플랫폼(RaaS)을 구독료 내고 임대해 손쉽게 공격을 감행함
* **암호화의 불가역성**: 군사/금융급 암호 알고리즘(RSA-2048 등)이 완벽히 적용되어, 해커의 개인키 없이는 수학적으로 복호화가 100% 불가능함

## Ⅴ. 개선방안
* **단기 방안 (3-2-1 백업 원칙)**: 3개의 데이터 복사본을, 2개의 다른 매체에 보관하고, 1개는 오프라인(망 분리) 상태로 보관하여 백업의 불변성(Immutability) 보장
* **중기 방안 (EDR 및 행위 기반 차단)**: 파일이 대량으로 변경되거나 볼륨 섀도 복사본을 삭제하는 등 랜섬웨어 특유의 이상 행위를 EDR이 실시간 탐지/차단
* **장기 방안 (제로 트러스트 아키텍처)**: RDP 포트 개방 등 불필요한 접근을 원천 차단하고, 모든 내부 통신도 인증/인가를 강제하는 최소 권한의 원칙 전사적용

## Ⅵ. 전망
* 백업 기술의 발전으로 암호화 공격이 무력화되자, 랜섬웨어 조직은 점차 암호화 없이 순수하게 '데이터 유출 협박(Data Extortion)'만으로 돈을 뜯어내는 형태로 전략을 선회 중임
* 피해 기업이 해커에게 돈을 지불해도 복호화 키를 받지 못할 확률이 높으므로, 각국 정부 지침은 절대 해상(협상)에 응하지 말 것을 강력히 권고하고 있음
