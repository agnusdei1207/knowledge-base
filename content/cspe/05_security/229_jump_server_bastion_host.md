# 📖 【암기용】 개념 완전 이해

> 목적: 점프 서버와 배스천 호스트를 처음 보는 사람도 관리자 접근을 왜 한 지점으로 모으는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 점프 서버는 내부 서버 관리자 접근을 중계·통제·기록하는 보안 관문이다.
- **왜 필요한가**: 운영자가 서버마다 SSH/RDP로 직접 접속하면 계정 공유, 접속 기록 누락, 권한 남용, 침해 확산을 추적하기 어렵다. 점프 서버는 접속 경로를 한곳으로 모아 인증, 권한, 세션기록, 명령통제를 수행한다.
- **핵심 직관**: 데이터센터 출입구에 보안검색대와 CCTV를 설치하고, 모든 작업자가 그 문으로만 들어가게 하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 클라우드, 온프레미스, 운영망에는 루트·Administrator·DBA 같은 특권계정이 존재한다. 이 계정이 탈취되면 서버 전체가 침해될 수 있으므로 접속 시작점부터 통제해야 한다.
- **작동 원리**: 사용자는 MFA와 승인 절차를 거쳐 점프 서버에 접속하고, 점프 서버는 PAM 정책에 따라 대상 서버 접근권한, 시간, 명령어, 파일전송을 제한한다. 모든 화면·명령·파일전송 로그는 감사 저장소에 남긴다.
- **비유**: 창고마다 열쇠를 나눠 주지 않고, 보안실에서 신분 확인 후 필요한 시간만 열쇠를 빌려 주고 CCTV로 기록하는 방식이다.
- **구체 예시**: 운영자는 22:00~23:00 장애조치 승인 후 MFA로 접속하고, `sudo systemctl restart app`만 허용된다. 세션 영상, 명령로그, 승인번호가 1년 보존된다.
- **흔한 오해·주의점**: 점프 서버를 만들기만 하면 특권접근관리가 끝나는 것이 아니다. 고가용성, 패치, JIT 권한, 세션기록 무결성, 우회 접속 차단을 함께 설계해야 한다.

## 연결 개념
- PAM — 특권계정 금고, 권한승인, 세션감사 통합
- Just-in-Time Access — 필요한 시간만 임시권한 부여
- Bastion Host — 외부에서 내부 관리망으로 들어가는 견고화된 중계 호스트

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 점프 서버 답안은 접속 중계가 아니라 특권접근의 인증, 승인, 명령통제, 세션녹화, 감사까지 포함해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Jump Server/Bastion Host는 관리자 접속을 단일 통제점으로 수렴해 특권계정 사용을 인증·인가·기록하는 보안 게이트웨이다.
> 2. **가치**: MFA, PAM, JIT, session recording, command control로 관리자 권한 남용과 침해 후 내부 이동을 추적한다.
> 3. **판단 포인트**: 대상 서버 직접접속 차단, 점프 서버 HA, 세션로그 무결성, break-glass 절차를 함께 설계한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 특권접근관리 이해 확인 | MFA, PAM, JIT, 세션녹화, 명령통제 | SSH 중계서버 수준으로만 설명 |
| 운영망 접근통제 설계 확인 | 관리자망 분리, 대상서버 직접접속 차단 | 우회 경로와 비상계정 절차 누락 |
| 감사·책임추적 역량 확인 | 사용자ID, 승인번호, 명령로그, 화면녹화 | 공용계정 허용 또는 로그 무결성 미설명 |

> 요약: 이 문제는 운영자 편의보다 특권계정 사용 근거와 행위를 감사 가능한 단위로 묶는 설계를 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 관리자 접속 단일 통제 관문
- 배경: 운영서버 직접접속은 특권계정 공유, 로그 누락, 권한 남용, 침해 확산의 원인이 되고 공용계정 사용 시 행위자 식별이 어려움
- 필요성: PAM·MFA·JIT·session recording을 적용하고 대상서버 직접접속 0건, MFA 적용률 100%, 세션기록 1년 이상 보존 기준으로 감사해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Admin User -> VPN/ZTNA -> MFA -> Jump Server
  / PAM Vault -> JIT Approval -> Target Server
  / Session Recording -> SIEM -> Audit Review
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MFA/VPN/ZTNA | 관리자 접속 전 신원·단말 검증 | FIDO2, OTP, 단말보안 점검 |
| Jump Server | SSH/RDP/DB 접속 중계 | 관리망에 배치, 직접접속 차단 |
| PAM Vault | 특권계정 보관과 비밀번호 회전 | 사용 후 즉시 회전, 공용계정 분리 |
| JIT Approval | 시간제 권한 승인 | 1~4시간 단위 임시권한 |
| Session Recording | 명령·화면·파일전송 기록 | 위변조 방지 저장, SIEM 연계 |

> 요약: 점프 서버는 신원검증, 권한승인, 접속중계, 세션기록, 감사분석이 연결된 특권접근 통제점이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접속 요청 -> MFA/단말검증 -> 작업 승인
  -> PAM 계정 발급 -> 점프 서버 접속
  -> 명령·파일 통제 -> 세션기록 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 관리자 신원, 단말, 위치 확인 | MFA 성공, 관리단말 등록 |
| 2 | 변경요청·장애티켓 기반 승인 | 승인번호, 시간창 1~4시간 |
| 3 | PAM이 계정·키를 주입하고 접속 중계 | 사용자에게 비밀번호 미노출 |
| 4 | 명령어, 파일전송, 클립보드 통제 | 금지명령 차단, 전송로그 기록 |
| 5 | 세션녹화와 로그 분석 | SIEM 상관분석, 감사리포트 생성 |

> 요약: 점프 서버 접근은 요청, 승인, 계정주입, 작업통제, 감사기록 순서로 처리된다.

## Ⅳ. 특징

| 구분 | 직접 관리자 접속 | 점프 서버·배스천 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 접속 경로 | 서버별 SSH/RDP 허용 | 단일 중계점 경유 | 대상서버 직접접속 0건 |
| 인증 | 계정·키 기반 | MFA, 단말, 위치 조건 | MFA 적용률 100% |
| 권한 | 상시 권한 | JIT 1~4시간 권한 | 만료 권한 자동회수 100% |
| 감사 | OS 로그 일부 | 화면녹화, 명령로그, 파일전송 | 세션기록 1년 이상 보존 |

> 요약: 점프 서버는 관리자 접근을 단일 경로로 제한하고 특권행위를 사용자와 승인근거에 연결한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 점프 서버·배스천 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 서버별 직접접속 | 관리망 단일 관문 | 운영서버 20대 이상 또는 규제대상 |
| 권한관리 | 공용계정, 키 공유 | PAM, JIT, 비밀번호 회전 | 특권계정 10개 이상 |
| 감사 | syslog 중심 | 세션녹화, 명령통제, SIEM 연계 | 감사추적 1년 이상 필요 |

> 요약: 운영서버와 특권계정 수가 늘수록 점프 서버 단독보다 PAM 통합형 구조가 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 단일 장애점 | 점프 서버 장애 | 이중화, DR, break-glass 절차 | 가용성 99.9%, RTO 30분 |
| 우회 접속 | 서버 보안그룹·ACL 허점 | 대상서버 inbound를 점프 서버 IP로 제한 | 직접접속 0건 |
| 로그 변조 | 관리자 권한으로 기록 삭제 | WORM 저장, 원격 로그, 해시검증 | 로그 무결성 검증 100% |

> 요약: 점프 서버는 통제점이므로 HA, 우회차단, 로그 무결성을 함께 설계해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 접속 통제 | MFA 100%, JIT 적용률 90% 이상 | PAM 리포트, IAM 로그 |
| 명령 통제 | 금지명령 차단률 100% | command policy 로그 |
| 감사 추적 | 세션녹화 100%, 로그보존 1년 이상 | SIEM, WORM 저장소 |

> 요약: 운영 효과는 MFA·JIT 적용률, 금지명령 차단률, 세션녹화 완전성으로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 서버 보안그룹과 방화벽에서 SSH/RDP inbound를 점프 서버 IP로만 허용해 직접접속을 0건으로 유지한다.
2. PAM과 연계해 MFA, 승인티켓, JIT 1~4시간 권한, 사용 후 비밀번호·SSH 키 회전을 적용한다.
3. 세션녹화, 명령로그, 파일전송 로그를 SIEM과 WORM 저장소에 연계하고 월 1회 특권접근 리뷰를 수행한다.

**결론 (2줄):**
- 기술사 판단: 운영서버가 20대 이상이거나 규제감사 대상이면 점프 서버와 PAM 통합이 필수이며, 소규모 환경도 직접접속 차단은 기본 통제다.
- 향후 방향: 배스천은 ZTNA, Just-in-Time Access, 클라우드 IAM과 결합되어 상시 특권을 제거하는 방향으로 전환된다.
