## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 관리자나 외주 개발자가 내부망 깊숙한 곳의 중요 서버(DB 등)에 직접 접속하는 것을 차단하고, 반드시 거쳐가도록 설계된 단일 통제 구역(보안 중계 서버)입니다.
- **필요성**: 수백 대의 서버에 관리자들이 제각각 접속하게 방치하면, 관리자 PC 한 대만 해킹당해도 전사 서버가 도미노처럼 뚫립니다. 접속 경로를 하나(Choke point)로 묶어 다중 인증(MFA)을 강제하고 모든 작업 내역을 CCTV처럼 녹화하기 위해 필수적입니다.
- **핵심 직관**: **"VIP 구역 전용 환승역(보안 검색대)"** - 외부에서 VIP 구역(DB 서버)으로 직행하는 도로는 모두 끊어버리고, 오직 삼엄한 보안 검색대가 있는 '환승역(점프 서버)'을 거쳐서만 VIP 구역행 전용 열차로 갈아탈 수 있게 만드는 통제 구조입니다.

## 2. 깊이 이해하기 (In-Depth Comprehension)
- **배경**: '배스천(Bastion)'은 중세 시대 성곽의 돌출된 요새를 의미하며, 초기 인터넷 방화벽 서버를 지칭했습니다. 오늘날에는 클라우드/내부망의 프라이빗 영역에 접근하기 위한 징검다리 서버(Jump Server)로 의미가 통합되었습니다.
- **작동 원리 (3박자 통제)**:
  - **네트워크 단절 (Jump)**: 관리자 PC $\rightarrow$ 타겟 서버 직통 통신 차단. 관리자는 점프 서버에 먼저 SSH 접속 후, 점프 서버 안에서 타겟 서버로 2차 접속 수행.
  - **권한 관리 (PAM, Privileged Access Management)**: 관리자는 점프 서버에만 로그인하고, 타겟 서버의 진짜 비밀번호는 모름(점프 서버가 자동 대리 로그인).
  - **세션 로깅 및 명령어 통제**: `rm -rf` 같은 치명적 명령어를 치는 순간 세션이 끊어지고, 모든 타이핑 내역(Keystroke)과 RDP 화면이 100% 녹화 및 저장됨.
- **비유**: 은행 직원이 금고에 갈 때 직접 열쇠를 따는 것이 아니라, '통제실(점프 서버)'에서 본인 인증(MFA)을 한 뒤 통제실의 로봇 팔(Auto-login)을 조종하여 작업하는 것. 모든 조종 내역은 블랙박스에 기록됩니다.
- **구체 예시**: AWS 환경에서 외부에 노출된 EC2(퍼블릭 서브넷)를 배스천 호스트로 삼고, 이를 통해서만 내부 프라이빗 서브넷의 DB(RDS)에 SSH/RDP 접근을 허용합니다. 배스천 호스트의 인바운드는 오직 '회사 본사 고정 IP'만 열어둡니다.
- **흔한 오해/주의점**: "점프 서버만 두면 안전하다?" $\rightarrow$ 단일 통로(SPOF/SPOC)이므로, 점프 서버 하나만 털리면 마스터키를 넘겨주는 것과 같습니다. 극단적인 서버 하드닝(Hardening)과 불필요한 패키지 제거가 생명입니다.

## 3. 연결 개념 (Related Concepts)
- **PAM (Privileged Access Management)**: 점프 서버의 기능을 소프트웨어로 고도화하여, 최고 권한 계정(Root/Admin)의 패스워드 은닉 및 세션 감사를 수행하는 솔루션.
- **Zero Trust Network Access (ZTNA)**: 최근 점프 서버(Inbound 포트 오픈)의 위험성조차 없애기 위해, 에이전트 기반의 역방향 터널링(Outbound 연결)으로 포트 없이 접속하는 차세대 패러다임 (예: AWS SSM).
- **DMZ**: 배스천 호스트가 위치하는 네트워크의 완충 지대.

# ✍️ 답안용 골격 (Exam Preparation)

### Ⅰ. 핵심 인사이트
- **본질**: 네트워크 경계(Perimeter)와 내부 핵심 시스템(Trust Zone) 사이의 유일한 접속 병목(Choke Point)으로 작용하여, 시스템 관리자의 원격 세션(SSH, RDP)을 강제 중계(Relay)하고 강력한 인증 및 로깅을 수행하는 통제 게이트웨이.
- **가치**: "관리자 권한의 오남용 방지 및 완벽한 감사 궤적(Audit Trail) 확보". ISMS-P 및 금융 컴플라이언스에서 요구하는 '최고 권한 계정 통제 및 작업 내역 보존' 의무를 가장 비용 효율적으로 해결하는 인프라 아키텍처.
- **판단 포인트**: 클라우드 아키텍트는 배스천 호스트가 지닌 '단일 침해점(SPOC)'의 위험을 인지하고, 인바운드 22번 포트를 전면 개방하는 대신 인가된 고정 IP만 허용하거나, 더 나아가 에이전트 기반의 포트리스(Portless) 제로 트러스트(AWS SSM 등)로 전환해야 함.

### Ⅱ. 배스천 호스트(점프 서버)의 4대 핵심 아키텍처 통제
```text
┌────────────────┐       ┌─────────────────┐       ┌────────────────┐
│ Admin PC       │       │ Bastion / PAM   │       │ Target Servers │
│ (Untrusted)    │  ==>  │ (Choke Point)   │  ==>  │ (Private Zone) │
└────────────────┘       └─────────────────┘       └────────────────┘
      1. 접속 라우팅 ──(방화벽 ACL 통제)──> 2. 터미널 프록시 연결
      3. 다중 인증(MFA) ─────────────> 4. 자동 대리 로그인 (비번 은닉)
      (명령어 통제/녹화) <──────────── (세션 I/O 스트리밍)
```
1. **접근 제어 (Access Control)**: 방화벽 정책(ACL)을 통해 타겟 서버(DB)는 점프 서버 IP의 접속만 허용(Direct 연결 차단).
2. **계정 은닉 (Credential Vault)**: 타겟 서버의 Root/Admin 비밀번호를 암호화 보관하고, 관리자에겐 자동 대리 로그인(Auto-login)만 제공.
3. **명령어 통제 (Command Filtering)**: 정규표현식 기반 화이트리스트/블랙리스트 통제로 악성/위험 명령어(`rm -rf` 등) 차단.
4. **세션 로깅 (Session Recording)**: 텍스트 기반 키스트로크(Keystroke) 로깅 및 GUI 기반 RDP 화면 녹화.

### Ⅲ. 클라우드 VPC 환경에서의 배스천 아키텍처
- **위치 선정**: 외부 인터넷 게이트웨이(IGW)와 통신 가능한 **Public Subnet**에 배치.
- **통신 흐름**:
  - 사용자 (본사 VPN IP 등 특정 IP 대역) $\rightarrow$ 인터넷 $\rightarrow$ IGW $\rightarrow$ 배스천 호스트 (Public IP) $\rightarrow$ 프라이빗 서버 (내부 사설 IP: 10.x.x.x 대역).
- **하드닝(Hardening) 필수 사항**: 최소 설치 옵션(Minimal OS), 불필요한 데몬 완전 삭제, 최신 커널 패치, 무조건 Key Pair(비대칭 키) 접속.

### Ⅳ. 최신 트렌드: 배스천 호스트의 종말 (ZTNA & SDP)
- **전통적 배스천 호스트의 한계**: 인바운드 포트(22번, 3389번)를 열어두어야 하므로 포트 스캐닝 및 제로데이 공격의 표적이 됨.
- **ZTNA (소프트웨어 정의 경계, SDP)로의 진화**:
  - 타겟 서버(프라이빗망) 내부에서 외부 클라우드 중계기를 향해 역방향(Outbound)으로 터널을 뚫는 에이전트(예: Cloudflare Tunnels) 설치.
  - 외부에서 서버로 들어가는 인바운드 포트를 100% 닫아놓은 상태(다크넷)에서도, 인증된 사용자는 프록시를 통해 안전하게 세션을 연결할 수 있음.

### Ⅴ. 결론 및 실무적 판단 포인트
- 인프라 보안 관리자는 외부 파트너(SI)가 내부망에 접근할 때 단순 VPN만 뚫어주는 구시대적 관행을 폐기해야 합니다. VPN은 성공 시 네트워크 전체(L3)에 대한 과도한 접근 권한을 부여합니다.
- 따라서 VPN(네트워크 접근)과 배스천 호스트(애플리케이션 계층 점프/PAM)를 결합하여, "인가된 개발자가 지정된 1대의 개발 서버"로만 마이크로 터널링을 하도록 통제(Zero Trust)하고, 작업 내역을 100% 모니터링해야만 공급망(Supply Chain)을 통한 랜섬웨어 수평 확산을 방어할 수 있습니다.

### 💡 문제 유형별 목차 전환 포인트
- **[내부자 위협(Insider Threat) 방어 및 권한 접근 통제(PAM) 아키텍처]**: Ⅰ과 Ⅱ(비밀번호 은닉, 명령어 통제)를 전면에 세워, 관리자 계정 탈취 및 악의적 행위에 대한 컴플라이언스(ISMS) 대응과 가시성 확보 방안 전개.
- **[클라우드 환경 원격 관리 보안 및 제로 트러스트(ZTA) 전환 동향]**: Ⅲ(VPC 배스천 설계)을 뼈대로 삼고 Ⅳ(ZTNA 포트리스 기술)를 엮어, "단일 장애점(SPOF) 리스크를 안고 있는 레거시 배스천 모델이, 방화벽 포트를 개방하지 않는 에이전트 기반 리버스 터널링으로 어떻게 혁신되고 있는가"에 대한 심화 엔지니어링 해법 서술.
