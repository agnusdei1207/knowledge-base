## Ⅰ. 개요
- **정의**: 모델의 출력(예측값·신뢰도)을 반복 질의하여 학습 데이터의 민감 정보를 복원하는 공격
- **배경/필요성**: 모델 API가 신뢰도 점수를 반환하면, 이를 역추적하여 학습 데이터 내 개인정보가 추론될 수 있음
- **비유**: 시험 답안지의 채점 결과만 보고 원래 문제와 정답을 역으로 알아내는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 프라이버시 위협 | 신뢰도 점수가 정보 유출 채널이 됨 | 모델 추출(140 참조)과 목적 구분 필요 |

> 요약: 모델 역전은 출력 신뢰도를 이용해 학습 데이터 내 민감 정보를 복원하는 프라이버시 공격임

## Ⅱ. 구성요소
```text
Target Model ---> Prediction API
                      |
                 Confidence Score
                      |
                      v
Attacker --> Optimization --> Reconstructed Data
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Prediction API | 모델의 분류·회귀 결과와 신뢰도를 반환하는 인터페이스 | 성적 조회 시스템 |
| Confidence Score | 각 클래스에 대한 확률 분포 | 과목별 세부 점수 |
| Optimization | 신뢰도를 극대화하는 입력을 반복 탐색하는 알고리즘 | 정답을 역추론하는 과정 |

> 요약: API의 신뢰도 점수를 최적화 알고리즘의 입력으로 활용하여 데이터를 복원함

## Ⅲ. 절차
```text
Query --> Collect --> Optimize --> Reconstruct
```
- 1단계: Query — 대상 모델에 다양한 입력을 반복 질의하여 출력을 수집함
- 2단계: Collect — 각 입력에 대한 신뢰도 점수·클래스 확률을 축적함
- 3단계: Optimize — 특정 클래스의 신뢰도를 극대화하는 입력 벡터를 경사 하강법으로 탐색함
- 4단계: Reconstruct — 최적화된 입력 벡터를 해석하여 학습 데이터의 근사치를 복원함

> 요약: 반복 질의 → 점수 수집 → 최적화 → 데이터 복원의 4단계로 공격이 수행됨

## Ⅳ. 문제점
- 신뢰도 노출: API가 상세 확률 분포를 반환하면 역전 공격의 정밀도가 높아짐
- 프라이버시 침해: 얼굴 인식·의료 모델에서 개인 식별 정보가 복원될 위험이 있음
- 탐지 곤란: 정상 추론 요청과 공격 질의를 구분하기 어려움

> 요약: 상세 신뢰도 노출, 개인정보 복원 위험, 탐지 곤란이 주요 문제임

## Ⅴ. 개선방안
1. 단기: API 응답에서 신뢰도 점수를 Top-K 라벨만 반환하거나 반올림 처리하여 정밀도를 낮춤
2. 중기: 차분 프라이버시(Differential Privacy)를 학습 과정에 적용하여 개별 데이터 영향을 희석함
3. 장기: API 질의 빈도·패턴을 모니터링하여 비정상 대량 질의를 탐지·차단하는 체계를 구축함

> 요약: 출력 정밀도 제한 → 차분 프라이버시 적용 → 질의 모니터링으로 다층 방어함

## Ⅵ. 전망
- 발전 방향: 생성형 AI 모델에서도 학습 데이터 복원 위협이 확인되어 방어 범위가 확대 중
- 기술사적 판단: 개인정보보호법·GDPR 등 규제와 연계하여 모델 API 보안이 의무화될 것임
- 기술사 제언: AI 서비스 API 설계 시 출력 정보량을 최소화하는 원칙을 적용할 필요
