# 📖 【암기용】 개념 완전 이해

> 목적: DSPM을 처음 보는 사람도 데이터 중심 보안 형상 관리가 왜 필요한지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: DSPM은 민감 데이터가 어디에 있고 누가 접근하며 어떤 위험에 노출되는지 지속 관리하는 체계임
- **왜 필요한가**: 클라우드와 SaaS에는 DB, Object Storage, Data Lake, 로그, 백업, AI 학습 데이터가 흩어진다. 인프라 설정만 보면 주민번호, 결제정보, 영업기밀이 실제로 노출되는지 판단하기 어렵다.
- **핵심 직관**: 서버를 지키는 것이 아니라, 금고 속 문서가 어느 서랍에 있고 누가 열람했으며 외부 복사본이 있는지 추적하는 방식임

## 깊이 이해
- **배경·문제의식**: CSPM은 버킷 공개, 보안그룹 오픈 같은 인프라 형상을 찾지만, 그 버킷 안에 개인정보 10만 건이 있는지 빈 테스트 파일만 있는지 구분하지 못한다. DSPM은 데이터 민감도와 접근 경로를 결합해 위험 우선순위를 정한다.
- **작동 원리**: 데이터 저장소를 탐색하고 샘플링 또는 메타데이터 분석으로 PII, PHI, PCI, 기밀문서를 분류한다. 이후 IAM, 공유 링크, 네트워크 노출, 암호화, 로그를 연결해 데이터별 노출 경로와 규제 위반 가능성을 계산한다.
- **비유**: 건물 보안팀이 문 잠금 상태만 보는 것이 아니라, 각 방의 문서 등급, 열람자, 복사 기록, 반출 승인 여부를 같이 대조하는 방식임
- **구체 예시**: S3 버킷에 주민등록번호 패턴 30만 건, 외부 계정 읽기 권한, SSE 미적용이 함께 발견되면 단순 버킷 이슈보다 GDPR/개인정보보호법 사고 후보로 우선 조치함
- **흔한 오해·주의점**: DSPM은 DLP와 동일하지 않다. DLP는 전송·반출 차단 중심이고, DSPM은 저장 위치, 민감도, 접근권한, 사용 이력, 규제 증거를 지속 평가함

## 연결 개념
- CSPM — 인프라 형상 위험을 탐지하며 DSPM은 데이터 민감도를 결합
- CIEM — 신원 권한 분석을 DSPM의 접근 가능성 판단에 사용
- DLP/Privacy — 반출 차단과 규제 증거를 DSPM 결과와 연계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: DSPM은 데이터 발견 도구가 아니라 민감도, 접근권한, 노출 경로, 규제 증거를 결합해 데이터 사고 가능성을 줄이는 운영 체계로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DSPM(Data Security Posture Management)은 분산 저장소의 민감 데이터를 발견·분류하고 접근권한·노출·암호화 상태를 지속 평가하는 데이터 중심 보안 관리 체계이다.
> 2. **가치**: CSPM이 인프라 오설정을 찾는다면 DSPM은 개인정보 10만 건, 외부 공유 링크, 미암호화 백업처럼 사고 영향이 큰 데이터 위험을 우선순위화한다.
> 3. **판단 포인트**: 데이터 위치, 민감도, 접근 주체, 노출 경로, 규제 매핑, 조치 SLA를 함께 제시해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 중심 보안 전환 이해 확인 | Discovery, Classification, Exposure, Access, Remediation | CSPM 또는 DLP와 동일시 |
| 클라우드 데이터 사고 대응 역량 확인 | Object Storage, DB, Data Lake, SaaS, 백업 데이터 위험 | 저장소 목록만 나열하고 민감도 누락 |
| 규제·감사 증거 설계 확인 | 개인정보보호법, GDPR, PCI DSS, 접근 로그, 암호화 증적 | 규제명 없이 "컴플라이언스 대응"으로 작성 |

> 요약: DSPM 문제는 데이터가 어디에 있고 누가 접근 가능하며 어떤 규제 위험으로 이어지는지를 연결하는 답안을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터 중심 보안 형상 관리
- 배경: 멀티클라우드와 SaaS 확산으로 민감 데이터가 DB, Object Storage, Data Lake, 로그, 백업에 분산됨.
- 필요성: ISO/IEC 27001 자산관리·접근통제 기준에 맞춰 민감도 분류, 노출 경로, 조치 증적을 데이터 단위로 관리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Data Sources -> Discovery -> Classification -> Access/Exposure Graph
  / Cloud DB, Object Storage, SaaS, Data Lake, Backup
Access/Exposure Graph -> Risk Scoring -> Remediation -> Audit Evidence
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Data Discovery | 저장소, 테이블, 파일, 백업 위치 식별 | AWS S3, RDS, BigQuery, SaaS API |
| Classification | PII, PHI, PCI, 기밀문서 분류 | 정규식, ML 분류, 사전 기반 탐지 |
| Access Graph | 사용자, Role, 공유 링크, 외부 계정 연결 | CIEM·IAM 로그와 결합 |
| Exposure Analysis | 공개 접근, 미암호화, 과도 권한 평가 | 인터넷 공개, Cross Account, Public Link |
| Remediation Engine | 권한 회수, 암호화, 마스킹, 티켓 발행 | SLA 24시간·72시간 기준 운영 |

> 요약: DSPM은 데이터 위치와 민감도에 접근 그래프를 결합해 조치 우선순위를 산정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
저장소 연결 -> 데이터 샘플링/메타데이터 수집 -> 민감도 분류
-> IAM/공유/네트워크 노출 분석 -> 위험 점수 산정
-> 권한 회수/암호화/마스킹 조치 -> 감사 증거 보관
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 클라우드·SaaS 저장소 인벤토리 수집 | 커버리지 95% 이상 |
| 2 | PII·PCI·PHI·기밀문서 탐지 및 태깅 | 오탐률 5% 이하 샘플 검수 |
| 3 | 접근권한, 공유 링크, 암호화, 로그 상태 분석 | 외부 공유 0건, SSE/KMS 적용률 100% |
| 4 | 위험 점수와 규제 항목 매핑 | GDPR·PCI DSS·개인정보보호법 증거 연결 |
| 5 | 조치 티켓, 권한 회수, 예외 만료 처리 | Critical SLA 24시간 이내 |

> 요약: DSPM은 발견, 분류, 노출 분석, 조치, 증거화 순서로 데이터 위험을 폐쇄한다.

## Ⅳ. 특징

| 구분 | 기존/대안 | DSPM | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 분석 대상 | 서버·네트워크·버킷 설정 | 데이터 객체·테이블·파일 단위 | 민감 데이터 건수, TB 단위 커버리지 |
| 위험 산정 | 공개 여부 중심 | 민감도+접근권한+노출 경로 | Critical 데이터 24시간 조치 |
| 통제 방식 | 방화벽, IAM, DLP 단일 통제 | 암호화, 권한 회수, 마스킹, 삭제 | KMS 적용률 100%, Public Link 0건 |
| 감사 증거 | 설정 스냅샷 | 데이터 분류표, 접근 로그, 조치 이력 | 월 1회 규제 매핑 리포트 |

> 요약: DSPM은 인프라 설정 점검을 넘어 민감 데이터별 노출 가능성과 사고 영향도를 기준으로 조치 순서를 정한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | DSPM | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | CSPM 중심 인프라 형상 관리 | 데이터 발견·분류·접근 그래프 | 데이터 저장소 50개 이상, SaaS 5개 이상 |
| 비용/범위 | 전수 스캔으로 비용 증가 | 메타데이터+샘플링+위험 기반 정밀 스캔 | 월 스캔 비용 예산과 민감도 등급 병행 |
| 운영/위험 | DLP 반출 이벤트 중심 | 저장 상태 위험과 규제 증거 관리 | PII·PCI 저장 위치 추적 필요 시 |

> 요약: 저장소가 분산되고 규제 데이터가 섞이면 CSPM 단독보다 DSPM을 결합해야 사고 영향도를 계산할 수 있다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Shadow Data | 임시 백업·분석 사본 방치 | 저장소 자동 발견, 소유자 태깅 | 미소유 데이터셋 0건 |
| 과도 접근 | 그룹 권한, 공유 링크, 외부 계정 | CIEM 연동, 90일 미사용 권한 회수 | 미사용 권한 회수율 95% |
| 분류 오탐 | 정규식 한계, 비정형 데이터 | 샘플 검수, ML 분류, 사전 보정 | 오탐률 5% 이하 |
| 규제 누락 | 데이터 흐름·거주지 미파악 | GDPR·PCI DSS·개인정보보호법 매핑 | 규제 미매핑 데이터 0건 |

> 요약: DSPM 운영 리스크는 Shadow Data, 과도 접근, 분류 오탐, 규제 누락이며 소유자·권한·증거 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 발견 커버리지 | 연결 저장소 95% 이상 | 클라우드 계정·SaaS API 인벤토리 대조 |
| 민감 데이터 통제 | Critical 데이터 Public Access 0건 | DSPM 대시보드, IAM 정책 검증 |
| 조치 SLA | Critical 24시간, High 72시간 | 티켓 처리 시간, 예외 만료 로그 |
| 감사 증거 | 월 1회 규제 매핑 리포트 | 분류표, 접근 로그, 암호화 설정 증적 |

> 요약: DSPM 성공 여부는 저장소 커버리지, Public Access 0건, SLA, 규제 증거의 네 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 1단계: AWS S3/RDS, Azure Blob/SQL, BigQuery, SaaS API를 연결하고 30일 내 저장소 커버리지 95% 확보
2. 2단계: PII·PCI·PHI 분류 정책을 정의하고 Critical 데이터의 Public Access 0건, KMS 암호화 100% 기준 적용
3. 3단계: CIEM·SIEM·티켓 시스템과 연동해 미사용 권한 90일 회수, Critical 조치 SLA 24시간 운영

**결론 (2줄):**
- 기술사 판단: 데이터 저장소가 50개 미만이면 CSPM+DLP로 시작하고, 멀티클라우드·SaaS·규제 데이터가 섞이면 DSPM을 CNAPP와 결합해야 함
- 향후 방향: 생성형 AI 학습 데이터, 벡터 DB, 프롬프트 로그까지 DSPM 범위에 포함해 데이터 계보와 사용 증거를 관리해야 함
