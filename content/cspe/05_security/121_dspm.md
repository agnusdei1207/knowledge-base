## 미리 알고가기

- 데이터 형상은 어디에 어떤 민감정보가 있고 누가 접근할 수 있는지를 합쳐 본 상태를 말함
- 데이터 분류는 개인정보, 재무정보, 소스코드처럼 보호 강도가 다른 정보를 구분하는 작업임
- 데이터 노출은 퍼블릭 공개, 과도 권한, 복제본 방치처럼 데이터가 불필요하게 드러난 상태를 말함

## Ⅰ. 개요

- **정의/개념**: DSPM은 클라우드와 SaaS에 흩어진 데이터를 찾아 민감도를 분류하고 접근 권한과 노출 상태를 분석해 데이터 중심으로 위험을 줄이는 관리 체계임
- **배경/필요성**: 클라우드 도입이 늘면서 데이터가 객체 저장소, 데이터 웨어하우스, 협업 SaaS에 복제되어 퍼지기 쉬워졌고 자산 설정만 봐서는 실제 민감정보 노출을 파악하기 어려워짐

## Ⅱ. 특징

- 인프라보다 데이터 자체를 기준으로 민감도와 노출 상태를 파악함
- 정형 데이터와 파일 데이터와 SaaS 저장 데이터를 함께 다룰 수 있음
- 과도 권한, 외부 공유, 암호화 누락, 장기 미사용 데이터까지 함께 봄
- 데이터 위치만 찾고 끝내지 않고 마스킹, 권한 축소, 보존기간 정리로 연결해야 효과가 남음

## Ⅲ. 종류 및 비교

| 판단 기준 | CSPM | DSPM |
|:---|:---|:---|
| 보는 중심 | 클라우드 리소스 설정 | 실제 저장된 데이터와 접근 권한 |
| 대표 질문 | 설정이 안전한가 | 민감정보가 어디에 있고 누가 보는가 |
| 강점 | 공개 노출과 설정 오류 점검 | 데이터 분류와 과도 권한 분석 |
| 함께 필요한 이유 | 바깥의 문을 잠금 | 안에 무엇이 있는지 확인함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 발견 | 스토리지, 데이터베이스, SaaS 저장소를 찾아 위치를 파악함 |
| 민감도 분류 | 개인정보, 재무정보, 인증정보 같은 보호 대상을 분류함 |
| 접근 분석 | 사용자와 서비스 계정 권한, 공유 링크, 외부 노출 여부를 확인함 |
| 위험 우선순위화 | 민감도, 공개 범위, 접근 주체 수를 기준으로 순서를 정함 |
| 보호 조치 | 마스킹, 암호화, 보존기간 정리, 권한 축소를 적용함 |

```text
데이터 저장소 탐색 -> 민감도 분류 -> 접근 권한 분석 -> 노출 위험 선별 -> 보호 조치
```

## Ⅴ. 원리 및 절차 흐름도

```text
저장소 연결 -> 민감정보 탐지 -> 권한과 공유 상태 분석 -> 위험도 산정 -> 보호 조치 -> 재스캔
```

1. **저장소 연결**: 객체 저장소, 데이터베이스, SaaS를 연결함
2. **민감정보 탐지**: 개인정보와 중요 문서를 식별해 분류함
3. **권한 분석**: 누가 읽고 쓰고 공유하는지 확인함
4. **위험도 산정**: 민감도와 노출 범위를 묶어 우선순위를 정함
5. **보호 조치**: 권한 축소와 암호화와 삭제 정책을 반영하고 다시 점검함

## Ⅵ. 실무 적용 및 유의점

1. 데이터 레이크와 객체 저장소가 많은 환경은 민감정보가 복제본으로 퍼지기 쉬우므로 DSPM으로 외부 공개 저장소와 과도 권한을 함께 줄이고 외부 공개 데이터 저장소 수와 장기 미사용 민감 데이터 양으로 확인함
2. 분석용 사본이 자주 생기는 조직은 원본만 보호해서는 부족하므로 복제 경로와 보존 기간을 함께 관리하고 암호화 적용률과 만료 후 삭제 지연 건수로 점검함

## Ⅶ. 결론

- DSPM은 스토리지를 지키는 관리가 아니라 데이터가 어디에 있고 누가 접근하는지를 드러내는 관리이므로 민감도 분류와 권한 분석이 함께 돌아가야 함
