# 📖 【암기용】 개념 완전 이해

> 목적: 동형 암호를 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 데이터를 복호화하지 않고 암호문 상태에서 연산하는 암호 기술
- **왜 필요한가**: 클라우드·AI 분석 사업자에게 원본 데이터를 맡기지 않고 통계, 검색, 추론 결과만 얻어야 하는 요구가 있다. 동형 암호는 데이터 처리자와 데이터 내용을 분리한다.
- **핵심 직관**: 잠긴 상자 안 숫자를 보지 못한 채 더하고 곱한 뒤, 주인만 열어서 결과를 확인하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 일반 암호는 저장·전송 중에는 데이터를 보호하지만 계산하려면 복호화가 필요하다. 이 순간 클라우드 관리자, 분석 서버, 메모리 덤프가 평문을 볼 수 있다.
- **작동 원리**: 평문을 격자 기반 암호문으로 바꾸고 암호문끼리 덧셈·곱셈을 수행한다. PHE는 덧셈 또는 곱셈 중 하나, SHE는 제한된 회로 깊이, FHE는 bootstrapping으로 잡음을 줄여 임의 회로를 처리한다.
- **비유**: 요리사가 재료 이름을 보지 못하고 밀봉된 봉투 번호만 조합해 조리표를 수행한 뒤, 손님만 봉투를 열어 완성 결과를 확인하는 구조다.
- **구체 예시**: 의료기관 10곳의 환자 수를 Paillier 방식으로 암호화해 합산하면 분석자는 각 병원 수치를 보지 못하고 총합만 복호화한다. FHE 기반 추론은 평문 대비 10배~1,000배 지연이 발생할 수 있다.
- **흔한 오해·주의점**: 동형 암호가 접근통제·키관리·결과 노출을 대신하지 않는다. 질의 결과가 너무 세밀하면 재식별 위험이 남아 차등 프라이버시와 결합해야 한다.

## 연결 개념
- 차등 프라이버시 — 동형 연산 결과의 재식별 위험을 잡음으로 통제
- MPC — 여러 참여자가 원본을 공개하지 않고 공동 계산하는 대안
- 기밀 컴퓨팅 — TEE 안에서 평문 계산을 수행하는 하드웨어 기반 대안

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 동형 암호는 암호문 상태에서 덧셈·곱셈을 수행해 데이터 처리자에게 평문을 노출하지 않는 PET 기술임.
> 2. **가치**: 클라우드 분석, 의료·금융 공동 통계, 암호화 검색에서 보호 대상 데이터와 계산 주체의 신뢰 경계를 분리함.
> 3. **판단 포인트**: PHE/SHE/FHE 유형, 회로 깊이, bootstrapping 비용, 암호문 팽창, 키관리, 결과 재식별 위험을 함께 평가해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 암호문 연산 원리 이해 | PHE, SHE, FHE, 덧셈·곱셈, bootstrapping | "암호화 후 분석"만 쓰고 잡음·회로 깊이 누락 금지 |
| 적용성 판단 | 클라우드 위탁 연산, 의료·금융 데이터, CKKS/BFV/BGV | 평문 대비 계산 비용을 빠뜨림 금지 |
| 보안 경계 설계 | 키 소유자, 계산 서버, 결과 수신자, 접근통제 | 결과값 재식별·키관리 리스크 누락 금지 |

> 요약: 동형 암호 답안은 암호문 연산 가능성과 성능 비용, 신뢰 경계, 결과 노출 통제를 동시에 제시해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 암호문 상태 연산 기술
- 배경: 클라우드·AI 분석 환경은 저장 중 암호화만으로 연산 시점의 평문 노출과 운영자 접근 위험을 제거하기 어려움.
- 필요성: 동형 암호는 데이터 소유자가 키를 보유하고 서버가 암호문만 계산하게 하여 의료·금융 위탁 분석의 평문 처리 범위를 줄임.

---

## Ⅱ. 구조 및 구성요소

```text
Data Owner -> KeyGen/Encrypt -> Ciphertext -> Compute Server
Compute Server -> Add/Mul/Evaluate -> Encrypted Result
Data Owner -> Decrypt -> Plain Result
/ Policy -> Key Management / Query Control / Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| KeyGen/Encrypt | 공개키·비밀키 생성, 평문 암호화 | 키는 데이터 소유자 또는 KMS/HSM 보관 |
| Evaluate | 암호문 덧셈·곱셈·회로 평가 | CKKS, BFV, BGV, Paillier |
| Noise control | 연산 중 잡음 관리 | modulus switching, bootstrapping |
| Decrypt/Policy | 결과 복호화·질의 통제 | 결과 재식별·감사로그 필요 |

> 요약: 동형 암호 구조는 키 소유자와 계산 서버를 분리하고, 암호문 평가와 잡음 제어를 통해 결과만 복호화하는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성 -> 평문 인코딩 -> 암호화 -> 암호문 연산
-> 잡음 확인 -> bootstrapping 선택 -> 결과 복호화 -> 재식별 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 보안 파라미터·스킴 선택 | NIST 128-bit security, 회로 깊이 |
| 2 | 평문 인코딩·암호화 | ciphertext expansion 배율 |
| 3 | 암호문 덧셈·곱셈 수행 | multiplicative depth, noise budget |
| 4 | 잡음 누적 시 bootstrapping 수행 | 연산 지연, 오류율 0건 |
| 5 | 결과 복호화·출력 통제 | 승인된 수신자, 질의 감사로그 |

> 요약: 동형 암호는 연산마다 잡음이 증가하므로 회로 깊이와 bootstrapping 비용을 설계 초기에 산정해야 함.

---

## Ⅳ. 특징

| 구분 | 기존 암호·TEE | 동형 암호 | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 노출 | 계산 시 평문 또는 enclave 내부 평문 | 서버는 암호문만 관측 | 운영자·메모리 공격 위협 모델 |
| 연산 범위 | 평문 프로그램 대부분 | 덧셈·곱셈 회로로 변환 필요 | 모델 구조, 회로 깊이 |
| 성능 비용 | 평문 기준 1배 | FHE는 10배~1,000배 지연 가능 | p95 지연, 처리량, 비용 |
| 적용 분야 | 일반 업무 처리 | 통계, 검색, 제한된 ML 추론 | 보호 데이터 민감도와 질의 수 |

> 요약: 동형 암호는 평문 노출을 줄이는 대신 회로 변환과 연산 비용을 감수하므로 고가치·저빈도 분석에 우선 적용함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | TEE, 서버 측 복호화 | 암호문 직접 연산 | 서버 운영자를 신뢰하지 않는 요구 |
| 비용/성능 | 평문 처리, ms 단위 | FHE 연산, ms~초 단위 | 배치 분석·비대화형 질의 |
| 운영/위험 | 접근통제 중심 | 키관리+질의 통제+결과 통제 | HSM, RBAC, DP 결합 여부 |

> 요약: 서버를 신뢰할 수 없고 지연 허용 범위가 초 단위인 분석 업무에 동형 암호를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 초과 | 회로 깊이·bootstrapping 과다 | SHE 우선, 모델 단순화, 배치 처리 | p95 지연, TPS, CPU 시간 |
| 키 노출 | 비밀키 중앙 보관 | HSM, 키 분리, rotation 90일 | 키 접근 감사 위반 0건 |
| 결과 재식별 | 소수 집단 질의 반복 | k 임계값, DP epsilon 관리 | 재식별 테스트 통과율 100% |

> 요약: 동형 암호 운영은 연산 비용, 키 보관, 결과 재식별 위험을 지표 기반으로 통제해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 성능 | 평문 대비 지연 배율, p95 응답시간 | 벤치마크, APM |
| 보안 | 128-bit security, 키 접근 0건 위반 | 파라미터 검토, HSM 로그 |
| 프라이버시 | 질의 최소 집단 k, epsilon 예산 | Privacy test, 감사로그 |

> 요약: 도입 성공은 암호 강도, p95 지연, 키 접근 통제, 재식별 테스트를 함께 만족할 때 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 업무를 합산·통계·추론으로 분류하고 Paillier, CKKS, BFV 중 회로 깊이와 정확도 오차 기준에 맞는 스킴 선정.
2. HSM 기반 비밀키 보관, RBAC, 키 rotation 90일, 질의 감사로그로 계산 서버와 키 소유자 신뢰 경계 분리.
3. PoC에서 p95 지연, 암호문 팽창률, noise budget, 재식별 테스트를 측정하고 epsilon 기반 결과 통제와 결합.

**결론 (2줄):**
- 기술사 판단: 고빈도 OLTP는 TEE·토큰화, 저빈도 민감 통계·암호화 추론은 동형 암호를 선택함.
- 향후 방향: FHE 컴파일러, GPU 가속, DP 결합으로 의료·금융 데이터 협업 분석에 적용 범위가 확대될 것임.
