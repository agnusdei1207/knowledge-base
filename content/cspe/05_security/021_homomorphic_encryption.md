# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 동형 암호는 **프라이버시 강화 기술(PET)** 중 하나로, 데이터를 복호화하지 않고 **암호문 상태에서 덧셈·곱셈 연산**을 수행해 처리 결과만 복호화하는 암호 기술임.
- **왜 필요한가**: 클라우드·AI 분석 환경에서 데이터를 서버에 맡기면 연산 시점에 평문이 노출됨. 동형 암호는 서버(계산 주체)가 평문을 전혀 보지 못하게 하여 데이터 소유자와 데이터 처리자의 신뢰 경계를 분리함.
- **핵심 직관**: 잠긴 상자 안 숫자를 보지 못한 채 더하고 곱한 뒤, 상자 주인만 열어서 결과를 확인하는 방식임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| PET (상위 키워드) | Privacy Enhancing Technologies — 개인정보 보호를 강화하는 기술 총칭 | 프라이버시 방어 도구 모음 |
| PHE | Partially HE — 덧셈 또는 곱셈 중 하나만 지원 | 덧셈만 되는 잠금 상자 (예: Paillier) |
| SHE | Somewhat HE — 제한된 횟수의 덧셈·곱셈 지원 | 횟수 제한 있는 상자 |
| FHE | Fully HE — 임의 회수의 덧셈·곱셈(임의 회로) 지원 | 제한 없는 상자 (bootstrapping 필요) |
| Bootstrapping | FHE에서 누적된 잡음(noise)을 줄여 추가 연산을 가능하게 하는 절차 | 상자를 새로 잠가 깨끗하게 리셋 |
| Noise Budget | 암호문에 남아 있는 잡음 여유량 — 0이 되면 복호화 불가 | 상자의 남은 내구도 |
| Multiplicative Depth | 곱셈 연산을 연속 수행할 수 있는 최대 횟수 | 상자를 흔들 수 있는 횟수 한계 |
| CKKS | 실수(근사값) 연산에 특화된 FHE 스킴 | 소수점 있는 계산용 상자 |
| BFV/BGV | 정수(정확값) 연산에 특화된 FHE 스킴 | 정수 계산용 상자 |
| Paillier | 덧셈 동형성만 지원하는 PHE 스킴 | 합산 전용 간단한 상자 |
| 암호문 팽창 | 평문 대비 암호문 크기가 커지는 비율 | 상자가 원래 물건보다 큰 것 |

## 깊이 이해
- **배경·문제의식**: 일반 암호(AES, RSA)는 저장·전송 중에만 데이터를 보호하고, 계산하려면 반드시 복호화해야 함. 이 순간 클라우드 관리자·분석 서버·메모리 덤프가 평문을 볼 수 있음. 의료·금융 데이터의 클라우드 위탁 분석, 개인정보 보호법의 위탁 처리 규제가 이 문제를 부각함.
- **작동 원리**: (1) 데이터 소유자가 공개키로 평문을 격자(lattice) 기반 암호문으로 변환함. (2) 계산 서버가 암호문끼리 덧셈·곱셈을 수행함 — 수학적으로 `Enc(a) ⊕ Enc(b) = Enc(a+b)`, `Enc(a) ⊗ Enc(b) = Enc(a×b)`가 성립함. (3) 연산마다 잡음(noise)이 누적되어 noise budget이 줄어듦. PHE는 한 연산만 지원하므로 잡음 관리가 단순하고, SHE는 제한된 회로 깊이까지 가능하며, FHE는 bootstrapping으로 잡음을 줄여 임의 깊이의 회로를 처리함. (4) 데이터 소유자만 비밀키로 결과를 복호화함.
- **비유**: 요리사가 재료 이름을 보지 못하고 밀봉된 봉투 번호만 조합해 조리표를 수행한 뒤, 손님만 봉투를 열어 완성 결과를 확인하는 구조임. 봉투를 너무 많이 흔들면(연산 과다) 내용물이 뭉개지므로(noise 초과) 중간에 새 봉투로 갈아 담아야(bootstrapping) 함.
- **구체 예시**: 의료기관 10곳의 환자 수를 Paillier(PHE)로 암호화해 합산하면 분석자는 각 병원 수치를 보지 못하고 총합만 복호화함. CKKS 기반 ML 추론은 평문 대비 10배~1,000배 지연이 발생할 수 있으며, 암호문 크기는 평문의 수십~수백 배로 팽창함.
- **흔한 오해·주의점**: (1) 동형 암호가 접근통제·키관리·결과 노출을 대신하지 않음 — 키 소유자·계산 서버·결과 수신자 간 신뢰 경계를 별도로 설계해야 함. (2) 질의 결과가 너무 세밀하면 소수 집단 재식별이 가능하므로 차등 프라이버시(024)와 결합해야 함. (3) TEE(025)와 용도가 겹치지만, TEE는 하드웨어 내부에서 평문 연산을, 동형 암호는 서버가 평문을 아예 보지 못하는 차이가 있음.

## 연결 개념
- **차등 프라이버시(024)**: 동형 연산 결과의 재식별 위험을 잡음(epsilon)으로 통제하는 보완 기술
- **안전한 다자간 연산 MPC(023)**: 여러 참여자가 원본을 공개하지 않고 공동 계산하는 대안 방식
- **기밀 컴퓨팅 TEE(025)**: 하드웨어 enclave 안에서 평문 계산을 수행하는 대안 — 서버 신뢰 모델이 다름

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 동형 암호는 암호문 상태에서 덧셈·곱셈을 수행해 데이터 처리자에게 평문을 노출하지 않는 PET 기술임.
> 2. **가치**: 클라우드 분석·의료/금융 공동 통계·암호화 검색에서 데이터 소유자와 계산 주체의 신뢰 경계를 분리함.
> 3. **판단 포인트**: PHE/SHE/FHE 유형·회로 깊이·bootstrapping 비용·암호문 팽창·키관리·결과 재식별 위험을 함께 평가해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 암호문 연산 원리 이해 | PHE/SHE/FHE 구분, 덧셈·곱셈 동형성, bootstrapping | "암호화 후 분석" 한 줄로 끝내고 잡음·회로 깊이 누락 |
| 적용성 판단 | 클라우드 위탁 연산, CKKS/BFV/BGV/Paillier 스킴 | 평문 대비 10~1000배 연산 비용 누락 |
| 보안 경계 설계 | 키 소유자·계산 서버·결과 수신자 분리, 접근통제 | 결과값 재식별·키관리 리스크 누락 |

> 요약: 동형 암호 답안은 암호문 연산 가능성과 성능 비용, 신뢰 경계, 결과 노출 통제를 동시에 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 암호문 상태에서 덧셈·곱셈을 수행해 평문 노출 없이 연산 결과를 산출하는 암호 기술임.
- 배경: 클라우드·AI 분석 환경에서 저장 중 암호화만으로는 연산 시점 평문 노출과 운영자 접근 위험을 제거하기 어려움.
- 필요성: 데이터 소유자가 키를 보유하고 서버가 암호문만 계산하게 하여 의료·금융 위탁 분석의 평문 처리 범위를 줄임.

---

## Ⅱ. 구조 및 구성요소

```text
Data Owner -> KeyGen/Encrypt -> Ciphertext -> Compute Server
Compute Server -> Add/Mul/Evaluate -> Encrypted Result
Data Owner -> Decrypt -> Plain Result
  / Policy -> Key Management / Query Control / Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| KeyGen/Encrypt | 공개키·비밀키 생성, 평문을 격자 기반 암호문으로 변환 | 키는 데이터 소유자 또는 KMS/HSM 보관 |
| Evaluate | 암호문 덧셈·곱셈·회로 평가 수행 | CKKS(실수)/BFV·BGV(정수)/Paillier(합산) |
| Noise Control | 연산 중 잡음 관리 — modulus switching, bootstrapping | FHE의 핵심 성능 병목 |
| Decrypt/Policy | 결과 복호화, 질의 통제, 감사로그 | 결과 재식별 방지·감사 필수 |

> 요약: 동형 암호 구조는 키 소유자와 계산 서버를 분리하고, 암호문 평가·잡음 제어를 거쳐 결과만 복호화하는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성(pk/sk) -> 평문 인코딩 -> 공개키 암호화
  -> 암호문 덧셈/곱셈 연산 -> Noise Budget 확인
  -> Bootstrapping(FHE) -> 결과 복호화 -> 재식별 점검
```

1. 파라미터 선택: 보안 수준(128-bit)·스킴(CKKS/BFV/Paillier)·회로 깊이(multiplicative depth)를 결정함.
2. 암호화·연산: 데이터 소유자가 평문을 인코딩·암호화하고, 계산 서버가 암호문끼리 덧셈·곱셈을 수행함 — 연산마다 noise가 누적됨.
3. 잡음 제어: noise budget 소진 시 bootstrapping을 수행해 추가 연산을 가능하게 함(FHE) — bootstrapping 1회에 수십 ms~수 초 소요됨.
4. 결과 복호화: 데이터 소유자가 비밀키로 결과를 복호화하고, 소수 집단 재식별 여부를 점검한 뒤 승인된 수신자에게 전달함.

> 요약: 동형 암호는 연산마다 잡음이 증가하므로 회로 깊이와 bootstrapping 비용을 설계 초기에 산정해야 함.

---

## Ⅳ. 특징

- 평문 노출 제거: 계산 서버가 암호문만 관측하므로 운영자·메모리 공격에 대한 평문 노출이 원천 차단됨.
- 연산 유형 제약: 모든 계산을 덧셈·곱셈 회로(arithmetic circuit)로 변환해야 하며, 분기·비교 연산은 회로 깊이를 급격히 증가시킴.
- 성능 비용: FHE 연산은 평문 대비 10~1,000배 지연이 발생하고, 암호문 크기는 평문의 수십~수백 배로 팽창함.
- 스킴별 트레이드오프: CKKS는 실수 근사 연산(ML 추론), BFV/BGV는 정수 정확 연산(투표·합산), Paillier는 덧셈 전용(간단 합산)에 각각 적합함.
- 결과 재식별 위험: 소수 집단에 대한 세밀한 질의를 반복하면 개인을 특정할 수 있으므로 차등 프라이버시(DP)와 결합 필요함.

---

## Ⅴ. 심화 비교 및 적용 판단

동형 암호(HE)와 기밀 컴퓨팅(TEE)을 신뢰 모델·성능·적용 범위 축으로 비교함.

| 구분 | 기밀 컴퓨팅(TEE) | 동형 암호(HE) | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 노출 | enclave 내부에서 평문 연산 | 서버는 암호문만 관측 | 서버 운영자 신뢰 수준 |
| 성능 비용 | 평문 기준 약 1.1~2배 오버헤드 | FHE 기준 10~1,000배 지연 | p95 지연·TPS 요구 수준 |
| 연산 범위 | 평문 프로그램 대부분 실행 | 덧셈·곱셈 회로로 변환 필요 | 모델 구조·회로 깊이 |
| 적용 분야 | 범용 업무 처리 | 통계·검색·제한된 ML 추론 | 데이터 민감도와 질의 빈도 |

> 요약: 고빈도 범용 연산은 TEE를, 서버 운영자를 신뢰할 수 없고 지연 허용이 초 단위인 민감 분석은 HE를 선택함.

**리스크·대응:**
- 성능 초과: 회로 깊이·bootstrapping 과다로 p95 SLA 초과 → SHE 우선 적용·모델 단순화·배치 처리 (지표: p95 지연, CPU 시간)
- 키 노출: 비밀키 중앙 보관 시 탈취 위험 → HSM 보관·키 분리·rotation 90일 (지표: 키 접근 감사 위반 0건)
- 결과 재식별: 소수 집단 질의 반복으로 개인 특정 → k 임계값·DP epsilon 예산 관리 (지표: 재식별 테스트 통과율 100%)

**도입 후 점검 지표:**
- 성능: 평문 대비 지연 배율·p95 응답시간 — 벤치마크·APM 측정
- 보안: 128-bit security 파라미터·키 접근 위반 0건 — 파라미터 검토·HSM 로그
- 프라이버시: 질의 최소 집단 k·epsilon 예산 — privacy test·감사로그

---

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 업무를 합산(Paillier PHE)·통계(BFV/BGV SHE)·ML 추론(CKKS FHE)으로 분류하고, 회로 깊이·정확도 오차 기준에 맞는 스킴을 선정함.
2. HSM 기반 비밀키 보관·RBAC·키 rotation 90일·질의 감사로그로 계산 서버와 키 소유자의 신뢰 경계를 분리함.
3. PoC에서 p95 지연·암호문 팽창률·noise budget·재식별 테스트를 측정하고, epsilon 기반 결과 통제(DP)와 결합함.

**결론:**
- 기술사 판단: 고빈도 OLTP는 TEE·토큰화를, 저빈도 민감 통계·암호화 추론은 동형 암호를 선택함.
- 향후 방향: FHE 컴파일러(HEIR, Concrete)·GPU 가속·DP 결합으로 의료·금융 데이터 협업 분석에 적용 범위가 확대될 것임.
