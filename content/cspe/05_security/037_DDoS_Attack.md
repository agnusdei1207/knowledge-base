## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 수많은 감염된 좀비 PC(봇넷)를 동원하여 타겟 서버에 대량의 트래픽을 전송함으로써 서비스를 마비시키는 분산 서비스 거부 공격임 |
| **배경/필요성** | 시스템 파괴나 정보 탈취가 아닌, 네트워크 대역폭과 서버 자원을 고갈시켜 비즈니스 연속성을 단절시키는 테러 행위 대응 필요 |
| **출제 의도** | 자원 고갈(SYN Flood, HTTP GET) 공격과 대역폭 고갈(DRDoS, UDP 증폭)의 원리 및 안티-DDoS 장비의 완화 기법 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
| SYN Flood (L4)    |      |  HTTP Flood (L7)  |      | DRDoS (반사 증폭) |
| (TCP 3-Way 대기)  +----->| (웹서버 부하 유발)+----->| (응답 크기 증폭)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **SYN Flood 공격 (L4)** | 위조된 IP로 수많은 SYN(연결 요청)만 보내고 ACK를 안 보내어 서버의 연결 대기 큐(Backlog)를 꽉 채우는 공격임 | 식당에 전화로 예약만 수만 번 걸고 나타나지 않음 |
| **HTTP Slowloris/Flood (L7)**| 정상적인 TCP 연결 후 매우 느리게 또는 엄청난 양의 웹 요청(GET/POST)을 보내 웹 서버의 스레드를 고갈시킴 | 식당 자리를 다 차지하고 물 한 잔만 시키며 버팀 |
| **반사 증폭 공격 (DRDoS)**| 공격 대상을 출발지 IP로 위조한 후 DNS/NTP 서버에 질의를 던져, 거대한 크기의 응답 트래픽이 대상에 쏟아지게 함 | 남의 이름으로 대량의 홈쇼핑 물건을 주문해 폭탄 배송 |

> 요약: 서버의 연결 허용량(L4), 애플리케이션 처리량(L7), 회선 대역폭(증폭)을 타겟팅하여 자원을 고갈시킴.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 봇넷 감염   |-->| 2. 공격 명령   |-->| 3. 대량 트래픽 |-->| 4. 서비스 마비 |
| (IoT기기 등)   |   | (C&C 서버 하달)|   | (타겟으로 집중)|   | (정상 접속 불가)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **봇넷 구축(감염)**: 공격자가 악성코드를 배포하여 수만 대의 개인 PC나 보안이 취약한 IoT 기기를 좀비(봇넷)로 감염시킴
2. **명령 하달(C&C)**: 공격자가 Command & Control 서버를 통해 특정 일시, 특정 타겟으로의 공격 명령을 좀비들에게 동시에 내림
3. **대량 트래픽 발생**: 봇넷들이 각자의 공격 유형(UDP 패킷 방플, SYN 요청 등)에 맞춰 무차별적으로 트래픽을 생성하여 발송함
4. **서비스 마비**: 타겟 서버 네트워크 회선이 꽉 차거나 방화벽/웹 서버의 자원이 100% 한계치에 도달하여 정상 사용자의 접속이 차단됨

> 요약: 감염된 거대 봇넷 부대를 지휘하여 동시다발적인 쓰레기 패킷을 쏟아부어 마비시키는 군해전술임.

## Ⅳ. 문제점
* **차단의 어려움(위조 IP)**: 공격 패킷의 IP 주소가 무작위로 위조(Spoofing)되거나 정상 트래픽과 섞여 있어 IP 기반 방화벽 차단이 거의 불가능함
* **대역폭 초과의 한계**: 수백 Gbps ~ Tbps 단위의 증폭 공격이 쏟아지면 기업 자체의 회선이나 온프레미스 보안 장비로는 감당할 수 없음
* **IoT 디바이스의 무방비성**: 비밀번호가 기본값으로 설정된 수많은 IP 카메라, 공유기 등이 봇넷(예: Mirai)으로 매우 쉽게 전락함

## Ⅴ. 개선방안
* **단기 방안 (SYN Cookie 및 임계치 설정)**: 서버에 연결 대기열을 관리하지 않는 SYN Cookie를 활성화하고 방화벽 단위당 연결 임계치 설정
* **중기 방안 (Anti-DDoS 장비 및 스크러빙 센터)**: 통신사(ISP) 상단에 위치한 대용량 트래픽 정제(Scrubbing) 센터로 트래픽을 우회시켜 악성만 거르고 정상 패킷만 내부망 수신
* **장기 방안 (클라우드 기반 CDN 분산 방어)**: 전 세계 엣지 노드에 트래픽을 분산 수용하고 Anycast 라우팅으로 공격을 흡수하는 클라우드 WAF/DDoS 방어 서비스 도입

## Ⅵ. 전망
* 5G 인프라와 수십억 대의 IoT 기기 연결로 인해 공격 가능한 봇넷 규모가 기하급수적으로 커져 테라급(Tbps) 공격이 일상화됨
* 이에 대응하여 클라우드 서비스 제공자(CSP)와 CDN 벤더들이 엣지 네트워크에서 대규모 공격을 원천 흡수하는 아키텍처가 방어의 기본이 됨
