## 미리 알고가기

- SAML은 XML 기반으로 인증 결과와 사용자 속성을 전달하는 연합 인증 표준임
- IdP는 사용자를 인증하는 기관이고, SP는 그 결과를 받아 서비스를 제공하는 쪽임
- 주 용도는 여러 기업 시스템에 한 번 로그인으로 접속하게 하는 엔터프라이즈 SSO임

## Ⅰ. 개요

- **정의/개념**: SAML 2.0은 IdP와 SP 사이에서 서명된 인증·속성 정보를 교환해 도메인 간 단일 로그인을 구현하는 연합 인증 표준임
- **배경/필요성**: 기업 업무 시스템은 여러 도메인과 제품으로 흩어짐. 계정과 로그인을 개별 관리하면 사용자 불편과 보안 부담이 커짐

## Ⅱ. 특징

- 기업 내부 포털과 SaaS 연동 같은 SSO 환경에 널리 쓰임
- XML 서명과 메타데이터 교환으로 신뢰 관계를 구성함
- IdP 중심 인증 통합으로 계정 관리 효율을 높임
- XML 처리와 서명 검증이 복잡해 구현 오류와 운영 부담이 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | SP-Initiated | IdP-Initiated |
|:---|:---|:---|
| 시작 위치 | 사용자가 서비스에 먼저 접근 | 사용자가 IdP 포털에서 시작 |
| 장점 | 접근 대상 서비스가 분명함 | 포털 기반 사용 편의가 좋음 |
| 유의점 | 요청과 응답 매칭 검증이 중요함 | 요청 없는 응답 처리에 대한 통제가 중요함 |
| 적합 환경 | 개별 서비스 직접 진입 | 사내 포털과 통합 대시보드 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Identity Provider | 사용자 인증과 SAML Assertion 발급을 담당함 |
| Service Provider | Assertion을 검증해 세션을 발급함 |
| SAML Assertion | 인증 결과와 속성을 담은 서명된 XML 토큰임 |
| Metadata and Certificates | 신뢰 관계와 서명 검증 기준을 제공함 |

```text
사용자 -> IdP 인증 -> SAML Assertion 발급 -> SP 전달 -> 서명 검증 -> 세션 발급
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 접근 -> IdP 리다이렉트 -> 사용자 인증 -> Assertion 발급 -> SP 검증 -> 로그인 완료
```

1. **서비스 접근**: 사용자가 SP에 접속함
2. **IdP 리다이렉트**: SP가 인증 필요 시 IdP로 보냄
3. **사용자 인증**: IdP가 계정과 MFA를 확인함
4. **Assertion 발급**: IdP가 서명된 SAML 응답을 생성함
5. **SP 검증과 로그인**: SP가 서명과 만료와 수신 대상을 확인하고 세션을 만듦

## Ⅵ. 실무 적용 및 유의점

1. 기업 SSO는 SAML 메타데이터와 인증서 갱신 절차를 관리하고 서명 검증 실패율·만료 인증서 사전 교체 여부로 확인함
2. XML 기반 구현은 XXE와 서명 래핑을 점검하고 악성 Assertion 재현 여부·전체 메시지 검증 정확도로 확인함

## Ⅶ. 결론

- SAML 2.0은 기업 연합 인증의 핵심 표준이므로 XML 처리와 서명 검증 복잡성을 정확히 다뤄야 안전한 SSO가 됨
