## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | XML 기반으로 인증·인가 정보를 교환하는 OASIS 표준으로, 도메인 간 SSO(Single Sign-On)를 구현하는 연합 인증 프로토콜임 |
| **배경/필요성** | 엔터프라이즈 환경에서 다수의 서비스(SP)에 개별 로그인하는 비효율을 제거하고, IdP 기반 중앙 인증이 필요함 |
| **출제 의도** | SAML의 SP-Initiated·IdP-Initiated 흐름과 OIDC와의 비교를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|   IdP    | --> | SAML     | --> |   SP     |
| (신원제공)|     | Assertion|     | (서비스) |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| IdP | 사용자를 인증하고 SAML Assertion을 발급하는 신원 제공자(Active Directory 등)임 | 여권 발급 기관 |
| SP | IdP가 발급한 Assertion을 검증하여 서비스 접근을 허용하는 서비스 제공자임 | 입국 심사대 |
| SAML Assertion | 인증·속성·권한 정보를 포함하는 XML 기반의 서명된 토큰임 | 비자가 찍힌 여권 |

> 요약: IdP(인증) → SAML Assertion(토큰) → SP(검증·허가)로 도메인 간 SSO를 구현함.

## Ⅲ. 절차
```
+------------+     +------------+
| SP접근요청  | --> | IdP로     |
| (사용자)   |     | 리다이렉트 |
+------------+     +------------+
                        |
+------------+     +----+-------+
| SP서비스   | <-- | Assertion |
| 접근허가   |     | 전달·검증  |
+------------+     +------------+
```

1. SP 접근: 사용자가 SP에 접근하면, SP가 인증되지 않은 요청을 감지함
2. IdP 리다이렉트: SP가 SAML AuthnRequest를 생성하여 사용자를 IdP로 리다이렉트함
3. IdP 인증: IdP에서 사용자가 로그인하면, IdP가 서명된 SAML Assertion을 생성함
4. Assertion 전달·검증: Assertion을 SP에 POST로 전달하고, SP가 서명·조건을 검증하여 세션을 발급함

> 요약: SP 접근 → IdP 인증 → Assertion 발급 → SP 검증으로 SP-Initiated SSO가 수행됨.

## Ⅳ. 문제점
- XML 파싱 취약점: SAML Assertion의 XML 처리 시 XXE·서명 래핑 공격에 노출될 수 있음
- 모바일 부적합: XML 기반 리다이렉트 흐름이 모바일 앱에서 구현이 복잡함
- 실시간 폐기 미지원: 발급된 Assertion의 유효 기간 내 즉시 폐기가 어려움

## Ⅴ. 개선방안
- (단기) 서명 검증 강화: Assertion 전체가 아닌 `SignedInfo`만 검증하는 래핑 공격을 방지하기 위해 정규화·서명 범위를 엄격히 검증함
- (중기) OIDC 병행: 모바일·SPA 서비스에는 OIDC를 적용하여 SAML과 병행 운영함
- (장기) IdP 통합 관리: 다수 IdP·SP 간 메타데이터를 자동 교환·갱신하는 페더레이션 허브를 구축함

## Ⅵ. 전망
- 신규 서비스에서는 OIDC가 주류이나, 엔터프라이즈 레거시 환경에서 SAML 2.0은 장기 공존하며 IdP 통합 허브를 통해 SAML↔OIDC 브리징이 표준화될 전망임
