## 미리 알고가기

- CTEM은 자산을 한 번 점검하는 활동이 아니라 공격 표면을 계속 찾고 검증하고 우선순위를 바꾸는 운영 체계임
- 노출 관리의 핵심은 취약점 개수보다 실제 악용 가능성과 업무 영향을 함께 판단하는 데 있음
- BAS와 침투 테스트는 CTEM의 일부 검증 수단일 뿐 전체 프레임워크를 대신하지 않음

## Ⅰ. 개요

- **정의/개념**: CTEM은 외부·내부 공격 표면을 지속 식별하고 악용 가능성을 검증해 조치 우선순위까지 연결하는 노출 관리 체계임
- **배경/필요성**: 클라우드, SaaS, 원격접속으로 자산과 설정이 수시로 바뀜. 정기 진단만으로는 실제 고위험 노출을 줄이기 어려움

## Ⅱ. 특징

- 자산 발견, 취약점 식별, 검증, 조치를 한 주기로 묶어 운영함
- CVSS 점수보다 공격 경로, 업무 영향, 외부 노출 여부를 함께 봄
- 보안팀 분석을 운영팀의 패치와 설정 변경까지 연결함
- 자산 목록이 부정확하면 대응 우선순위가 왜곡됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 정기 취약점 관리 | CTEM |
|:---|:---|:---|
| 운영 주기 | 월간·분기 단위 점검 중심 | 지속적 식별과 재평가 |
| 우선순위 기준 | 취약점 개수와 점수 중심 | 악용 가능성 + 업무 영향 중심 |
| 검증 방식 | 스캔 결과 중심 | BAS, 침투 테스트, 경로 검증 포함 |
| 운영 목표 | 목록화와 패치 추적 | 실제 노출 감소와 대응 연계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Scoping | 중요 서비스, 자산군, 외부 노출 범위를 정의해 관리 대상을 좁힘 |
| Discovery | 자산, 계정, 포트, API, 설정 오류, 취약점을 식별함 |
| Prioritization | 악용 가능성, 공격 경로, 업무 영향으로 대응 순서를 정함 |
| Validation | BAS, 침투 테스트, 시나리오 검증으로 실제 악용 가능성을 확인함 |
| Mobilization | 운영팀과 개발팀에 조치 과제를 배정하고 추적함 |

```text
범위 정의 -> 자산/노출 발견 -> 위험 우선순위화 -> 악용 가능성 검증 -> 조치 실행/재평가
```

## Ⅴ. 원리 및 절차 흐름도

```text
자산 변화 수집 -> 외부/내부 노출 식별 -> 위험 점수 조정 -> 검증 수행 -> 조치 배포 -> 재측정
```

1. **자산 변화 수집**: 클라우드, 네트워크, 애플리케이션 자산 변화를 모음
2. **노출 식별**: 취약점, 설정 오류, 과도 권한, 외부 공개 자산을 찾음
3. **위험 점수 조정**: 업무 중요도와 공격 가능성을 반영해 우선순위를 다시 매김
4. **검증 수행**: 자동화 공격 시뮬레이션이나 수동 테스트로 실제 악용 가능성을 확인함
5. **조치와 재측정**: 패치와 설정 변경을 적용하고 남은 노출을 다시 확인함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 환경은 외부 공개 여부, 계정 권한, 공격 경로를 함께 우선순위화하고 동일 경로 재현 실패·고위험 노출 감소율로 확인함
2. BAS·침투 테스트 결과는 자산 목록과 조치 추적 체계에 묶고 패치 SLA 준수율·티켓 종료 시간으로 확인함

## Ⅶ. 결론

- CTEM은 취약점 목록화가 아니라 실제 공격 가능한 노출을 줄이는 운영 체계이므로 자산 변화, 검증, 조치 연결이 핵심임
