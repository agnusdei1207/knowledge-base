# 📖 【암기용】 개념 완전 이해

> 목적: DMZ를 처음 보는 사람도 인터넷, DMZ, 내부망이 왜 나뉘는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: DMZ는 인터넷 공개 서비스와 내부 업무망 사이에 두는 완충 네트워크 구간이다.
- **왜 필요한가**: 웹, 메일, DNS처럼 외부에 열어야 하는 서버를 내부망에 두면 침해 시 DB와 업무시스템까지 이동 경로가 생긴다. DMZ는 외부 노출 자산을 별도 구간에 묶어 피해 범위를 줄인다.
- **핵심 직관**: 회사 로비처럼 외부인은 출입 가능하지만 사무실 내부로 바로 들어가지 못하게 막는 구역이다.

## 깊이 이해
- **배경·문제의식**: 인터넷 서비스는 80/443, SMTP, DNS 포트를 열어야 한다. 내부망과 같은 구간에 두면 웹 취약점 하나가 내부 lateral movement로 이어질 수 있다.
- **작동 원리**: Internet -> External Firewall -> DMZ -> Internal Firewall -> Internal Network로 구간을 나누고, DMZ에는 reverse proxy, WAF, web, mail relay, external DNS를 둔다. 내부 DB 접근은 필요한 포트와 방향만 허용한다.
- **비유**: 택배 기사는 건물 로비까지만 들어오고, 내부 사무실 문은 별도 출입증과 담당자 확인이 있어야 열리는 구조다.
- **구체 예시**: 외부 사용자는 WAF를 통해 DMZ reverse proxy 443/tcp에 접속하고, proxy는 내부 WAS 8443/tcp만 호출한다. DB 1521/tcp는 DMZ에서 직접 접근하지 못하게 차단한다.
- **흔한 오해·주의점**: DMZ는 Zero Trust와 같은 개념이 아니다. DMZ는 네트워크 구간 분리이고, Zero Trust는 사용자·기기·세션 조건을 매 요청마다 검증하는 접근 원칙이다.

## 연결 개념
- WAF — HTTP 요청 검사와 OWASP Top 10 공격 차단
- Reverse Proxy — 외부 요청을 내부 서비스 대신 받아주는 중계 지점
- East-West 통제 — DMZ 내부 서버 간 이동과 내부망 접근 제한

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: DMZ 답안은 구간 위치만 설명하지 않고 공개 서비스, 방화벽 ACL, 내부 접근 제한, Zero Trust와 차이를 함께 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DMZ는 인터넷 공개 서버를 내부망과 분리해 외부 침해의 내부 확산을 제한하는 중간 보안 구간이다.
> 2. **가치**: web, mail, DNS, reverse proxy, WAF를 DMZ에 배치하고 내부망 접근은 최소 포트·단방향 정책으로 제한한다.
> 3. **판단 포인트**: North-South 방화벽 ACL뿐 아니라 DMZ 내부 East-West 이동, 관리자 접근, 로그 수집까지 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 네트워크 보안구역 설계 이해 확인 | Internet-DMZ-Internal 3계층, 이중 방화벽 | DMZ를 단순 서버존으로만 설명 |
| 공개 서비스 보호 역량 확인 | WAF, reverse proxy, mail relay, external DNS | 내부 DB 직접 공개 또는 any-any ACL |
| Zero Trust와 관계 판단 확인 | DMZ는 구간분리, ZT는 요청별 검증 원칙 | DMZ 도입만으로 세션 검증을 대체한다고 단정 |

> 요약: DMZ 문제는 공개 서비스 배치와 내부망 확산 차단을 ACL·프록시·로그 지표로 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 외부 공개 서비스 완충망
- 배경: 웹·메일·DNS 같은 인터넷 서비스는 외부 접속을 허용해야 하므로 내부 업무망과 같은 구간에 두면 침해 후 DB·업무시스템으로 이동 경로가 생김
- 필요성: Internet-DMZ-Internal 3계층에서 External/Internal FW, WAF, reverse proxy를 배치하고 DMZ -> 내부 DB 직접 접근 0건 기준으로 검증해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Internet -> External FW -> DMZ
  / WAF -> Reverse Proxy -> Web/Mail/DNS
  / Internal FW -> App/API -> Internal DB
  / SIEM -> Log Archive
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| External Firewall | 인터넷에서 DMZ로 들어오는 포트 제한 | 80/443, 25, 53 등 허용목록 |
| WAF/Reverse Proxy | HTTP 검사와 내부 서비스 중계 | OWASP Top 10 룰, TLS 종료 |
| Public Server | web, mail relay, external DNS 제공 | 내부 DB 직접 연결 금지 |
| Internal Firewall | DMZ에서 내부망 접근 제한 | 목적지·포트·방향 최소화 |
| SIEM/Log | 접속·탐지·차단 이벤트 수집 | 1년 이상 원본로그 보존 |

> 요약: DMZ는 외부 방화벽, 공개 서비스, 내부 방화벽, 로그 수집이 결합된 완충 보안구간이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
외부 요청 수신 -> External FW ACL 검사
  -> WAF/Proxy 검사 -> DMZ 서비스 처리
  -> Internal FW 최소포트 허용 -> 내부 API 호출
  -> 로그 수집·상관분석
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 외부 접속의 목적지·포트 확인 | 허용 포트 80/443/25/53 제한 |
| 2 | WAF에서 HTTP 헤더·본문·업로드 검사 | OWASP CRS 룰 적용 |
| 3 | Reverse Proxy가 내부 서비스 대리 호출 | 내부 IP 비노출, TLS 1.2 이상 |
| 4 | Internal FW가 내부 접근 최소 허용 | DMZ -> DB 직접 접근 0건 |
| 5 | 로그 수집과 탐지 룰 적용 | 차단로그, 관리자 접근로그 보존 |

> 요약: DMZ 트래픽은 외부 ACL, 애플리케이션 검사, 내부 ACL, 로그 분석 순서로 통제된다.

## Ⅳ. 특징

| 구분 | 단일 내부망 공개 | DMZ 분리 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 공격면 | 내부망 서비스 직접 노출 | 공개 서비스만 외부 노출 | 인터넷 공개 포트 5개 이하 |
| 확산 통제 | 침해 후 내부 이동 가능 | Internal FW로 이동 제한 | DMZ -> 내부 허용룰 10개 이하 |
| 운영 복잡도 | 정책 단순 | 이중 방화벽·로그 운영 필요 | ACL 리뷰 월 1회 |
| 보안 모델 | 경계 의존 | 경계+프록시+탐지 | WAF 탐지율, SIEM 상관분석 |

> 요약: DMZ는 공개 서비스 노출을 허용하되 내부망 접근을 최소 포트와 방향으로 제한하는 구조다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | DMZ | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 내부망 직접 공개 | Internet-DMZ-Internal 3계층 | 인터넷 공개 서비스 1개 이상 |
| 접근통제 | 단일 방화벽 | 이중 방화벽, WAF, proxy | 개인정보·결제·업무DB 분리 필요 |
| Zero Trust | 네트워크 위치 중심 | DMZ+신원·세션 검증 병행 | 원격관리·API 접근 증가 시 |

> 요약: DMZ는 네트워크 구간 보호에 유효하며, 사용자·기기 검증은 Zero Trust 통제로 보완한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| DMZ 우회 | VPN, 관리포트 외부노출 | 관리자망 분리, PAM, MFA | 외부관리포트 0개 |
| 내부 확산 | DMZ -> 내부 ACL 과다 | 목적지·포트 최소화, 마이크로세그먼트 | 허용룰 10개 이하 |
| 로그 공백 | WAF/FW 로그 미수집 | SIEM 연계, NTP 동기화 | 로그 수집률 99% 이상 |

> 요약: DMZ 운영 리스크는 우회접근, 내부확산, 로그공백이며 정책 수와 로그 수집률로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| ACL 최소화 | any-any 0건, 미사용룰 0건 | 방화벽 정책 리뷰 |
| 공개서비스 보호 | WAF 적용률 100%, TLS 1.2 이상 | WAF 콘솔, SSL 스캔 |
| 확산 차단 | DMZ -> 내부 DB 직접접근 0건 | NetFlow, FW 로그 |

> 요약: DMZ 성공 여부는 ACL 최소화, WAF 적용률, 내부 직접접근 차단 건수로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 인터넷 공개 서비스는 DMZ에 배치하고 External FW에서 80/443/25/53 등 필요한 포트만 허용한다.
2. 웹 서비스는 WAF와 reverse proxy를 경유하게 하고 내부 WAS/API 접근은 Internal FW에서 목적지·포트 단위로 제한한다.
3. 관리자 접근은 VPN+MFA+PAM으로 분리하고 FW/WAF/proxy 로그를 SIEM에 연계해 1년 이상 보존한다.

**결론 (2줄):**
- 기술사 판단: 외부 공개 서비스가 있으면 DMZ는 기본 설계이며, 내부 API·DB 직접 공개가 필요한 구조는 설계 오류로 판단한다.
- 향후 방향: DMZ는 Zero Trust, 마이크로세그먼테이션, WAF API 보호와 결합되어 구간 경계와 세션 검증을 함께 적용한다.
