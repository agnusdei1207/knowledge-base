## 미리 알고가기

- RBAC는 사용자에게 권한을 직접 하나씩 주는 대신 역할에 권한을 묶고 사용자를 그 역할에 배정하는 방식임
- 역할은 직무나 책임 범위를 뜻하며, 권한은 읽기·수정·승인 같은 실제 행위를 뜻함
- 핵심은 개별 권한 난립을 줄이는 데 있지만 역할이 너무 많아지면 오히려 관리가 어려워질 수 있음

## Ⅰ. 개요

- **정의/개념**: RBAC는 업무 역할을 기준으로 권한을 묶고 사용자에게 역할을 부여해 접근 권한을 간접 관리하는 접근 제어 모델임
- **배경/필요성**: 사용자와 시스템이 늘면 개별 권한 직접 관리는 오류와 누락이 많아짐. 직무 중심 권한 표준화가 필요함

## Ⅱ. 특징

- 직무 기준으로 권한을 재사용해 관리 효율을 높임
- 입사·이동·퇴사 때 역할 변경만으로 권한 정리가 쉬움
- 역할 설계가 세밀해질수록 역할 수가 급증할 수 있음
- 시간·위치·기기 상태 같은 동적 조건은 단독 RBAC로 다루기 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 권한 부여 | RBAC |
|:---|:---|:---|
| 관리 단위 | 사용자별 권한 | 역할별 권한 |
| 장점 | 예외 처리가 단순할 수 있음 | 표준화와 대량 관리에 유리함 |
| 한계 | 규모가 커질수록 혼선이 큼 | 역할 폭발과 예외 관리가 문제됨 |
| 적합 환경 | 소규모 시스템 | 조직형 업무 시스템과 백오피스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Users | 실제 시스템을 사용하는 계정임 |
| Roles | 직무나 책임에 대응하는 권한 묶음임 |
| Permissions | 리소스에 대해 허용된 행위 목록임 |
| Assignment Rules | 어떤 사용자에게 어떤 역할을 줄지 정하는 기준임 |

```text
사용자 -> 역할 할당 -> 역할에 매핑된 권한 -> 리소스 접근 허용/거부
```

## Ⅴ. 원리 및 절차 흐름도

```text
직무 분석 -> 역할 정의 -> 권한 매핑 -> 사용자 할당 -> 정기 리뷰와 회수
```

1. **직무 분석**: 어떤 업무가 어떤 자원에 접근해야 하는지 정리함
2. **역할 정의**: 공통 직무를 역할로 묶음
3. **권한 매핑**: 각 역할에 필요한 권한만 부여함
4. **사용자 할당**: 입사자나 이동자에게 역할을 연결함
5. **정기 리뷰**: 필요 없는 역할과 예외를 회수함

## Ⅵ. 실무 적용 및 유의점

1. ERP·그룹웨어는 RBAC로 기본 권한을 표준화하고 역할 중복 감소·퇴직·이동 후 권한 회수 적시성으로 확인함
2. 프로젝트 예외가 많은 환경은 예외 역할을 최소화하고 역할 폭발 여부·임시 역할 만료 준수율로 확인함

## Ⅶ. 결론

- RBAC는 접근 제어를 직무 단위로 정리하는 기본 모델이므로 역할 설계와 정기 정리가 함께 있어야 관리 효율이 유지됨
