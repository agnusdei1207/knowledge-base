## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 사용자에게 직접 권한을 부여하지 않고, 직무 역할(Role)에 권한을 매핑한 뒤 사용자를 역할에 할당하여 접근을 제어하는 모델임 |
| **배경/필요성** | 사용자 수 증가 시 개별 권한 관리가 비현실적이며, 역할 단위 관리로 권한 부여·회수의 효율성을 확보해야 함 |
| **출제 의도** | RBAC의 계층 모델(RBAC0~3)과 ABAC과의 비교를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 사용자   | --> |  역할    | --> |  권한    |
| (User)   |     | (Role)   |     | (Permission)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 사용자 | 시스템에 접근하는 주체로, 하나 이상의 역할에 할당됨 | 회사 직원 |
| 역할 | 직무·직책에 대응하는 권한의 집합으로, 사용자와 권한 간 중간 계층임 | 직책(과장·부장) |
| 권한 | 특정 리소스에 대한 읽기·쓰기·실행 등 조작 허가임 | 직책별 결재 한도 |

> 요약: 사용자→역할→권한의 3계층 구조로, 역할 단위의 효율적 접근 제어를 구현함.

## Ⅲ. 절차
```
+------------+     +------------+
| 역할정의   | --> | 권한매핑   |
| (직무분석) |     | (Role-Perm)|
+------------+     +------------+
                        |
+------------+     +----+-------+
| 접근제어   | <-- | 사용자할당 |
| 적용       |     | (User-Role)|
+------------+     +------------+
```

1. 역할 정의: 조직의 직무를 분석하여 역할(관리자·운영자·사용자 등)을 정의함
2. 권한 매핑: 각 역할에 필요한 최소 권한을 매핑함(최소 권한 원칙 적용)
3. 사용자 할당: 사용자를 적절한 역할에 할당하고, 직무 변경 시 역할을 재할당함
4. 접근 제어 적용: 리소스 접근 시 사용자의 역할-권한을 실시간 검증하여 허가·거부를 결정함

> 요약: 역할 정의 → 권한 매핑 → 사용자 할당 → 접근 제어로 체계적 권한 관리를 수행함.

## Ⅳ. 문제점
- 역할 폭발: 세분화된 권한 요구에 따라 역할 수가 기하급수적으로 증가(Role Explosion)함
- 동적 권한 미지원: 시간·위치·컨텍스트에 따른 유연한 접근 제어가 어려움
- 직무 분리 검증: 상충하는 역할의 동시 할당(SoD 위반)을 수동으로 관리해야 함

## Ⅴ. 개선방안
- (단기) 역할 계층화: RBAC1(역할 상속)을 적용하여 하위 역할이 상위 권한을 상속받아 역할 수를 줄임
- (중기) ABAC 혼합: 컨텍스트 기반 조건(시간·IP·디바이스)을 RBAC에 결합하여 동적 제어를 보완함
- (장기) 정책 엔진 도입: OPA(Open Policy Agent) 등으로 RBAC·ABAC을 통합한 PBAC으로 진화함

## Ⅵ. 전망
- RBAC은 엔터프라이즈 접근 제어의 기반으로 유지되나, ABAC·PBAC과 결합하여 제로 트러스트 환경의 세밀한 동적 접근 제어 모델로 진화할 전망임
