# 📖 【암기용】 개념 완전 이해

> 목적: 생체 인식을 지문·얼굴을 저장하는 기능이 아니라 생체 특징 추출, 템플릿 비교, 위조 탐지, 프라이버시 통제가 결합된 인증 방식으로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 지문, 얼굴, 홍채 같은 신체·행동 특징을 템플릿으로 변환해 등록자와 제시자를 비교하는 인증 기술
- **왜 필요한가**: 비밀번호는 재사용·피싱·유출 위험이 있고, OTP는 분실·중계 공격이 존재한다. 생체 인식은 사용자가 가진 고유 특징으로 단말 잠금 해제, 출입, 금융 인증의 사용자 확인을 수행한다.
- **핵심 직관**: 사진 자체를 저장하는 것이 아니라 사진에서 특징점 지도를 뽑아 잠금장치 안에서 비교하는 방식임

## 깊이 이해
- **배경·문제의식**: 지식 기반 인증은 기억 부담과 유출 재사용 문제가 있다. 생체 인증은 사용성 측면에서 장점이 있지만, 생체 정보는 비밀번호처럼 쉽게 교체할 수 없어 템플릿 보호와 위조 탐지가 필수이다.
- **작동 원리**: 등록 단계에서 센서가 생체 샘플을 수집하고 특징 벡터를 추출해 템플릿을 생성한다. 인증 단계에서는 새 샘플을 템플릿과 비교해 matching score가 임계값을 넘으면 성공으로 판정한다.
- **비유**: 열쇠 모양 전체를 복사해 보관하지 않고, 자물쇠 안에 홈과 돌기의 패턴만 저장한 뒤 새 열쇠의 패턴과 맞추는 구조임
- **구체 예시**: 스마트폰은 얼굴 원본 이미지를 앱 서버로 보내지 않고, Secure Enclave/TEE에서 얼굴 템플릿과 matching score를 계산해 FIDO2 서명 사용을 허용한다.
- **흔한 오해·주의점**: 생체 인식은 100% 판정이 아니다. FAR, FRR, EER 임계값 조정이 필요하고, 사진·마스크·실리콘 지문 공격을 막기 위해 ISO/IEC 30107 PAD를 적용해야 한다.

## 연결 개념
- FIDO2/WebAuthn — 생체 인식을 로컬 사용자 검증 수단으로 사용
- Presentation Attack Detection — 사진·영상·마스크 등 위조 제시 탐지
- Template Protection — cancelable biometrics, secure sketch, 암호화 저장
- 개인정보보호 — 민감정보 처리, 동의, 목적 제한, 보관 기간 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 생체 인증은 센서 정확도만이 아니라 FAR/FRR, PAD, 템플릿 보호, 로컬 처리, 대체 인증 절차를 함께 설계해야 하는 고위험 인증 수단임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 생체 인식은 신체·행동 특징을 템플릿으로 변환하고 matching score와 임계값으로 등록자 여부를 판단하는 인증 기술이다.
> 2. **가치**: 비밀번호 입력을 줄이고 피싱 재사용 위험을 낮추되, 생체 원본·템플릿 보호와 위조 제시 탐지를 필수 통제로 둔다.
> 3. **판단 포인트**: FAR, FRR, EER, PAD, TEE/HSM, 개인정보 동의, 장애·오탐 시 대체 인증을 정량 지표로 관리해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생체 인증 절차 이해 확인 | 등록, 특징 추출, 템플릿 저장, matching, 임계값 | 원본 이미지 저장으로 단순 설명 |
| 보안·프라이버시 판단 확인 | PAD, 템플릿 암호화, 로컬 처리, 동의 | 생체는 유출되지 않는다고 단정 |
| 지표 기반 운영 확인 | FAR, FRR, EER, spoof acceptance, fallback | 정확도만 쓰고 오탐·미탐 누락 |
> 요약: 이 문제는 생체 인식의 편의성보다 위조 탐지와 템플릿 보호를 정량 지표로 설명해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 생체 특징 기반 사용자 확인
- 배경: 비밀번호·OTP는 피싱, 재사용, 분실, 중계 공격에 노출되며 생체 정보는 유출 후 재발급이 어렵다.
- 필요성: ISO/IEC 19794 템플릿 형식과 FIDO2 로컬 사용자 검증처럼 템플릿 보호, liveness detection, FAR/FRR 지표 관리가 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
Sensor -> Feature Extraction -> Template Store -> Matcher -> Decision
           +-> PAD / Liveness
           +-> TEE / Encryption / Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Sensor | 지문·얼굴·홍채 샘플 수집 | 해상도, 조명, 오염 영향 |
| Feature Extraction | minutiae, face embedding, iris code 추출 | 원본 이미지 저장 최소화 |
| Template Store | 생체 템플릿 암호화 보관 | TEE, Secure Enclave, HSM |
| Matcher | 입력 샘플과 등록 템플릿 비교 | score, threshold, FAR/FRR |
| PAD | 사진·영상·마스크·실리콘 위조 탐지 | ISO/IEC 30107 기반 |
> 요약: 생체 인증 구조는 센서, 특징 추출, 템플릿 저장, 매칭, 위조 탐지가 결합된 판단 파이프라인이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
등록 샘플 수집 -> 특징 추출 -> 템플릿 암호화 저장
-> 인증 샘플 수집 -> PAD 확인 -> 매칭 점수 계산 -> 허용 / 거절 / 대체 인증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 등록 시 생체 샘플 2~3회 수집 | 품질 점수, 중복 등록 여부 |
| 2 | 특징 벡터 추출 및 템플릿 생성 | 원본 폐기, 템플릿 암호화 |
| 3 | 인증 시 새 샘플과 liveness 확인 | PAD pass, spoof score 임계값 |
| 4 | matcher가 score와 threshold 비교 | FAR 0.001%, FRR 1% 목표 |
| 5 | 실패 시 fallback과 감사 로그 처리 | 대체 인증, 실패 로그 보존 |
> 요약: 생체 인증은 등록 템플릿과 인증 샘플을 비교하되, PAD와 임계값 조정으로 위조·오탐을 통제한다.

## Ⅳ. 특징

| 구분 | 비밀번호·OTP | 생체 인증 | 정량·기술 포인트 |
|:---|:---|:---|:---|
| 사용자 확인 | 지식·소유 기반 | 신체·행동 특징 기반 | FAR 0.001%, FRR 1% 목표 |
| 피싱 대응 | 입력값 중계 가능 | 로컬 매칭+FIDO2 서명 가능 | WebAuthn user verification |

| 공격면 | 피싱, OTP 중계 | 사진·마스크·실리콘 지문 | ISO/IEC 30107 PAD |
> 요약: 생체 인증은 입력 재사용 공격을 줄이지만, 템플릿 유출과 위조 제시 공격을 별도 통제로 다뤄야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 생체 인증 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 비밀번호, OTP, 인증서 | 센서, 템플릿, matcher, PAD | 로컬 사용자 검증과 피싱 저항 필요 |
| 비용/성능 | 서버 검증 중심 | 센서·TEE·PAD 모델 필요 | unlock p95 1초 이하, FRR 1% 이하 |
| 운영/위험 | 재설정 가능 | 생체 템플릿 유출, 위조 제시 | 템플릿 보호, fallback, 동의 절차 |
> 요약: 생체 인증은 단말 로컬 검증과 피싱 저항이 필요한 경우 적합하고, 원격 대량 식별은 법적 근거와 별도 통제가 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 위조 제시 | 사진, 영상, 마스크, 실리콘 지문 | PAD, depth sensor, challenge-response | spoof acceptance 0.1% 이하 |
| 템플릿 유출 | 서버 저장, 암호화 미흡 | TEE/HSM, cancelable biometrics, 원본 폐기 | 원본 저장 0건, 암호화 100% |
| 오탐·차별 | 조명, 피부 상태, 연령, 장애 | 임계값 조정, fallback, 편향 테스트 | 그룹별 FRR 차이 2%p 이하 |
> 요약: 생체 인증 리스크는 위조 수용률, 템플릿 보호율, 그룹별 오류율로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 정확도 | FAR 0.001%, FRR 1%, EER 1% 이하 | ISO/IEC 19795 평가 |
| 위조 탐지 | PAD 통과 위조율 0.1% 이하 | ISO/IEC 30107 테스트 |
| 개인정보 통제 | 원본 저장 0건, 템플릿 암호화 100% | 저장소 점검, DPIA |
> 요약: 생체 인증 도입 평가는 FAR/FRR/EER, PAD 위조율, 템플릿 저장 통제로 수행한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 단말 로컬 처리: Secure Enclave/TEE에서 템플릿 매칭을 수행하고 서버에는 FIDO2 assertion만 전달해 원본 생체 전송 0건 유지
2. 위조 탐지 적용: ISO/IEC 30107 PAD, depth sensor, challenge-response를 적용하고 spoof acceptance 0.1% 이하로 운영
3. 프라이버시 통제: 명시 동의, 목적 제한, 원본 폐기, 템플릿 암호화 100%, fallback 인증과 삭제 요청 절차를 문서화

**결론 (2줄):**
- 기술사 판단: 단말 잠금 해제·FIDO2 사용자 검증에는 생체 인증을 적용하고, 중앙 원격 식별은 법적 근거·DPIA·PAD 지표 확보 후 제한 적용한다.
- 향후 방향: 패스키, 온디바이스 AI, liveness detection이 결합되어 생체 원본을 서버로 보내지 않는 로컬 검증 구조가 확대된다.
