## Ⅰ. 개요
- **정의**: 지문, 홍채, 얼굴 등 개인의 고유 생체 특징을 측정하여 본인 여부를 확인하는 인증 방식임
- **배경/필요성**: 비밀번호는 유출·재사용·망각 문제가 있으므로 분실 불가능한 본인 고유 특징 기반 인증이 필요함
- **비유**: 열쇠 대신 주인의 얼굴을 인식해 문을 여는 스마트 도어락과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생체 인증의 정확도 지표와 보안 위협 | FAR/FRR/EER 개념 구분 | 생체정보 유출 시 변경 불가 문제 |

> 요약: 생체 인증은 개인 고유의 생물학적 특징으로 본인을 확인하는 인증 방식임

## Ⅱ. 구성요소
```text
센서 -> 특징 추출 -> 템플릿 비교 -> 판정
  |         |             |           |
생체입력  알고리즘     등록 DB      FAR/FRR
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 센서 | 지문 스캐너, 카메라, 마이크 등 생체 데이터를 수집하는 장치 | 출입구 카메라 |
| 특징 추출 엔진 | 원본 생체 데이터에서 고유 특징점을 수학적으로 추출하는 모듈 | 얼굴 윤곽 측정기 |
| 템플릿 DB | 등록 시 생성된 생체 특징 템플릿을 보관하는 저장소 | 회원 명부 |
| 매칭 알고리즘 | 입력 특징과 등록 템플릿 간 유사도를 산출하여 판정하는 엔진 | 대조 심사관 |
| FAR/FRR | 타인 수락률(FAR)과 본인 거부률(FRR)을 나타내는 정확도 지표 | 판정 엄격도 척도 |

> 요약: 센서 수집, 특징 추출, 템플릿 매칭, FAR/FRR 기반 판정으로 생체 인증을 수행함

## Ⅲ. 절차
```text
생체 등록 -> 데이터 수집 -> 특징 매칭 -> 인증 판정
```
- 1단계: 사용자가 센서를 통해 생체 데이터를 입력하고 특징 템플릿을 등록(Enrollment)함
- 2단계: 인증 요청 시 센서가 생체 데이터를 실시간 수집함
- 3단계: 특징 추출 엔진이 입력 데이터의 특징점을 산출하고 등록 템플릿과 유사도를 비교함
- 4단계: 유사도가 임계값 이상이면 인증 성공, 미만이면 거부 판정을 내림

> 요약: 등록, 수집, 매칭, 판정의 4단계로 생체 기반 본인 확인이 완료됨

## Ⅳ. 문제점
- 템플릿 유출 시 변경 불가: 비밀번호와 달리 생체 특징은 재발급이 불가능함
- 환경 의존 오류: 센서 상태, 조명, 피부 상태 등 외부 환경에 따라 FRR이 증가함
- 프라이버시 침해: 생체정보는 민감정보로 수집·저장 시 법적 규제 대상임

> 요약: 변경 불가성, 환경 의존 오류, 프라이버시 침해가 생체 인증의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 취소 가능 생체정보(Cancelable Biometrics) 변환을 적용하여 원본 유출 위험을 제거함
2. 중기: 다중 모달 생체 인증(지문+얼굴)을 결합하여 환경 의존 오류를 보완함
3. 장기: FIDO2(091 참조) 기반 온디바이스 매칭으로 생체 템플릿의 서버 저장을 완전 제거함

> 요약: 취소 가능 변환, 다중 모달, 온디바이스 매칭으로 생체 인증 보안을 강화해야 함

## Ⅵ. 전망
- 발전 방향: Passkey와 결합하여 패스워드리스 인증의 핵심 수단으로 확산될 전망임
- 기술사적 판단: 온디바이스 처리 중심으로 프라이버시와 편의성을 동시에 달성하는 방향으로 수렴할 것임
- 기술사 제언: 조직은 생체정보 처리 시 개인정보보호법의 민감정보 처리 규정을 준수해야 함
