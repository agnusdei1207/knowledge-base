## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 반도체 공장, 자동차 조립 라인 등 공장의 기계들을 제어하는 **'OT(운영 기술, Operational Technology)망'이 인터넷(스마트 팩토리)과 연결되면서 해커에게 노출되는 치명적 위협을 방어하고, 기계가 멈추거나 폭발하지 않도록 가용성(Availability)을 최우선으로 지켜내는 산업용 보안 체계**입니다.
- **필요성**: 과거의 공장은 인터넷 선을 뽑아둔 '갈라파고스 섬(에어갭)'이어서 외부 해킹이 불가능했습니다. 하지만 공장을 똑똑하게(스마트 팩토리) 만들려고 공장 기계와 사무실(IT망), 클라우드를 하나로 연결하기 시작했습니다. 그 결과, 사무실 직원이 잘못 누른 랜섬웨어가 공장 설비로 퍼져 수천억 원짜리 반도체 생산 라인이 멈추는 대참사가 일어나기 시작했습니다.
- **핵심 직관**: **"무인도(공장)에 다리(인터넷)를 놓았을 때 벌어지는 일"**. 
  - 과거 (단절): 공장 기계는 오래된 윈도우 XP를 썼지만, 육지와 다리가 없어서(폐쇄망) 바이러스가 올 수 없었음.
  - **스마트 팩토리 (연결의 저주)**: 육지(IT망)와 다리를 놓자마자 육지의 도둑(해커)들이 건너와 공장 기계를 멈춰버림. 공장 기계는 백신도 없고 패치도 못 해서 한 방에 뻗음. $\rightarrow$ 방어법: 다리 중간에 **"데이터가 육지로만 나갈 수 있고, 육지에서 섬으로는 못 들어오게 하는 일방통행 게이트(단방향 망연계)"** 를 설치해야 함.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 대만의 글로벌 반도체 위탁 생산 기업인 TSMC의 생산 라인이 2018년 '워너크라이(WannaCry)' 랜섬웨어에 감염되어 사흘간 멈추며 약 3,000억 원의 손실을 보았습니다. 기계를 돌리는 구형 윈도우 7 PC에 보안 패치를 하지 않았고, USB 관리가 허술했기 때문입니다. 이 사건은 전 세계 제조업계에 "스마트 팩토리의 이점(효율)보다 보안 사고(공장 중단)의 손실이 1,000배 더 크다"는 뼈저린 교훈을 남겼습니다.
- **가치**: "기밀성(C)보다 가용성(A)의 절대 우위". 일반 IT 기업은 해킹당하면 서버 전원을 끕니다(기밀 유지). 하지만 제철소 용광로나 화학 공장은 전원을 끄면 폭발하거나 쇳물이 굳어버립니다(재난). 따라서 OT 보안은 무슨 일이 있어도 **'설비의 지속 가동(Availability)'과 '사람의 안전(Safety)'** 을 지키는 것이 유일한 절대 가치입니다.

## 3. 어떻게 작동하는가? (Mechanism)
OT 보안은 일반 PC 방어와 완전히 다릅니다. '퍼듀 모델(Purdue Model)'이라는 층 나누기 아키텍처를 씁니다.

1. **퍼듀 모델 (Purdue Model) 기반의 망분리**
   - 레벨 4, 5: 사무실과 인터넷 망 (Enterprise IT 망)
   - 레벨 3: 공장 운영 서버 망
   - 레벨 0, 1, 2: 실제 기계, 로봇 팔, 밸브(PLC, 센서) (순수 OT 망)
   - 핵심 메커니즘: 각 레벨 사이사이에 **산업용 방화벽(Industrial Firewall)** 을 쳐서, 레벨 4(사무실)에서 터진 랜섬웨어가 레벨 2(로봇 팔)로 절대 넘어오지 못하게 차단(Segmentation)합니다.
2. **단방향 통신 (일방통행 게이트웨이, Data Diode)**
   - 공장 기계의 센서 데이터(온도, 불량률)를 사무실(IT)이나 클라우드에서 봐야 스마트 팩토리가 돌아갑니다.
   - 이때 양방향으로 뚫어두면 해커가 들어오므로, 하드웨어적으로 전선(광케이블)을 한쪽으로만 연결하여 **"공장 $\rightarrow$ 사무실로 데이터 전송만 가능, 사무실 $\rightarrow$ 공장으로는 데이터 유입 절대 불가(물리적 차단)"** 하도록 단방향 보안 장비를 달아버립니다.
3. **심층 패킷 분석 (DPI)과 화이트리스트 백신**
   - 공장 기계는 백신 업데이트를 할 수 없습니다(재부팅 불가). 
   - 그래서 "무엇이 바이러스인지(블랙리스트)" 찾는 일반 백신 대신, "허락된 딱 3개의 프로그램만 실행하고 나머지는 모조리 차단"하는 **화이트리스트(Whitelist)** 기반 솔루션을 씁니다.
   - 또한, 공장 통신망에 흐르는 특수 언어(Modbus 등)를 해독할 수 있는 OT 전용 침입 탐지 시스템(IDS)을 달아 이상한 명령(예: "온도를 1000도로 올려라")을 즉각 차단합니다.

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례 (USB를 통한 에어갭 파괴 방어)**: 
  - 외부 유지보수 직원이 공장에 들어와 "기계 업데이트할게요"라며 자기 주머니에서 꺼낸 USB를 공장 메인 컨트롤러(HMI)에 꽂는 순간, 그 안에 있던 악성코드가 공장을 셧다운시킵니다.
  - 이를 막기 위해 공장 입구에 **'키오스크(Kiosk) 검사대'** 를 설치합니다. 직원은 반드시 자기 USB를 키오스크에 먼저 꽂아 백신 엔진 3개로 검사를 받고, 검사가 끝난 파일만 공장용 특수 USB(또는 망연계 시스템)로 옮겨 담아 기계에 꽂아야 하는 엄격한 **매체 제어(Device Control) 프로세스**를 강제합니다.
- **주의점 및 흔한 오해**: 
  - "IT팀에서 쓰던 방화벽이나 백신을 그냥 공장에 갖다 깔면 안 되나요?" $\rightarrow$ **절대 안 됩니다. 공장이 멈춥니다.**
  - IT 백신은 의심스러운 파일을 발견하면 팝업을 띄우고 지우거나 CPU를 100% 써서 검사합니다. 공장(OT)에서 이렇게 CPU가 느려지면 로봇 팔이 1밀리초(ms) 늦게 멈춰서 제품이 다 부서집니다. OT 장비는 반드시 **가용성에 1%의 영향도 주지 않는 패시브(Passive/미러링) 모니터링 방식이나 OT 전용 장비**를 써야 합니다.

## 5. 핵심 비교 및 연결 개념 (Relation)
IT(사무실) 보안 vs OT(공장/설비) 보안의 철학 차이:
| 비교 항목 | IT 보안 (Information Technology) | **OT 보안 (Operational Technology)** |
|---|---|---|
| **최우선 목표 (CIA)** | **기밀성 (Confidentiality - 유출 방지)** | **가용성 (Availability - 멈추지 마라!)** |
| **운영체제 (OS)** | Windows 10/11, Linux (최신 OS) | 윈도우 XP, 윈도우 7, RTOS (레거시, 구형) |
| **패치 및 재부팅** | 매주 정기 패치, 마음대로 재부팅 가능 | **20년간 재부팅 금지 (패치 불가능)** |
| **사고 발생 시 조치** | 서버 전원 끄고 랜선 뽑기 (네트워크 차단) | **전원 끄면 대폭발. 절대 끄면 안 됨.** |
| **보안 솔루션** | 능동형 EDR, 백신 (Active) | **수동적(Passive) 모니터링, 망분리, 화이트리스트** |

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 생산성 향상과 데이터 기반 의사결정(스마트 팩토리/Industry 4.0)을 위해 폐쇄망이었던 산업 제어 시스템(ICS/SCADA)과 공장 운영 기술(OT: Operational Technology) 망이 기업의 IT 망 및 외부 인터넷 클라우드와 융합(IT-OT Convergence)되면서 발생하는, 물리적 설비 파괴 및 생산 라인 중단 위협에 대응하는 **가용성(Availability) 및 안전(Safety) 최우선 기반의 산업 보안 아키텍처.**
- **가치**: "사이버 위협의 물리적/재무적 임팩트 최소화". 기존 IT 해킹이 개인정보 유출(과징금)에 그쳤다면, 랜섬웨어가 스마트 팩토리의 생산 조립 라인(PLC 제어기)이나 반도체 웨이퍼 라인을 타격할 경우, 단 몇 시간의 정지(Downtime)만으로도 수백~수천억 원의 직접적인 매출 손실과 설비의 물리적 파괴를 초래합니다. 워너크라이(WannaCry) 감염으로 3천억 원의 손실을 본 대만 TSMC 사태나 르노/닛산 공장 가동 중단 사태는, IT 망의 보안 위협이 언제든 측면 이동(Lateral Movement)을 통해 OT 망의 붕괴로 이어질 수 있음을 입증하는 치명적 교훈입니다.
- **판단 포인트**: IT 보안 아키텍트는 공장/제어망에 일반 사무용 백신이나 IPS(침입방지시스템)를 설치하는 만용(Active Intervention)을 부려서는 안 됩니다. OT 망의 핵심은 '실시간성(Real-time)'입니다. 백신의 시그니처 검사로 인해 제어 신호가 1ms만 지연(Latency)되거나 재부팅이 발생해도 공정 불량이 발생합니다. 따라서 OT 보안 아키텍처는 시스템 리소스와 네트워크 대역폭에 개입하지 않는 **아웃 오브 밴드(Out-of-Band) 형태의 네트워크 미러링(Mirroring) 기반 심층 패킷 분석(DPI)과 허용된 프로세스만 실행하는 애플리케이션 화이트리스팅(Application Whitelisting) 방식**으로 설계(Design)되어야 합니다.

### Ⅱ. IT/OT 보안 패러다임의 근본적 차이 (CIA Triad 역전)
가장 많이 출제되는 뼈대. 왜 접근법이 다른가?
- **IT (Information Technology)**: C-I-A 우선순위. **기밀성(Confidentiality)** 최우선. 정보가 유출될 바엔 차라리 시스템 전원을 끄고(가용성 포기) 통신망을 끊음. 3~5년 주기 하드웨어 교체, 수시 패치(Patch) 적용.
- **OT (Operational Technology)**: A-I-C 우선순위. **가용성(Availability)과 무결성(안전성, Safety)** 최우선. 시스템이 멈추거나 오작동하면 물리적 재난(폭발, 환경 오염)이 발생하므로 절대로 끄면 안 됨. 정보 유출(기밀성)은 후순위. 10~20년 주기 롱텀 사용, 24시간/365일 무중단 운영으로 패치/재부팅 불가(레거시 OS 방치).

### Ⅲ. 스마트 팩토리 보안 아키텍처 설계: 퍼듀 모델 (Purdue Model)
IT-OT 융합 환경의 논리적 망분리 글로벌 표준 (ISA-95/IEC 62443 기반).
1. **아키텍처 구조 (계층적 방어)**
   - **Level 4/5 (Enterprise IT Zone)**: 회사 사무망, 메일 서버, 외부 인터넷망. (랜섬웨어 감염의 주된 시작점).
   - **Level 3.5 (IDMZ - 산업용 비무장지대) ★핵심 방어선**: IT망과 OT망 사이의 완충 지대. 패치 관리 서버나 터미널 서버가 위치하며, IT망에서 OT망으로 직접 통신(Direct Connection)을 원천 차단.
   - **Level 3 (Operations Support)**: 공장 전체의 관제 시스템(SCADA Master), 제조 실행 시스템(MES).
   - **Level 1/2 (Control / Supervisory)**: HMI(모니터링 패널), PLC(프로그래밍 가능한 논리 제어기, 기계의 뇌).
   - **Level 0 (Process / Device)**: 센서, 액추에이터, 로봇 팔, 밸브 (물리적 제어단).
2. **방어 메커니즘**
   - 레벨 간의 통신은 반드시 방화벽(FW)이나 단방향 전송 장비(Data Diode)를 거쳐 엄격히 통제(Segmentation)되어야 하며, 특히 Level 3.5(IDMZ)를 우회하는 모든 네트워크 경로는 차단되어야 함.

### Ⅳ. OT 보안의 3대 핵심 기술 솔루션
에어갭(Air-gap) 파괴 시대의 대응 방안.
1. **단방향 망연계 장비 (Unidirectional Gateway / Data Diode)**
   - 스마트 팩토리 구현을 위해 OT(공장)의 센서 데이터를 IT(클라우드 빅데이터 서버)로 넘겨야 할 때 사용.
   - 하드웨어의 송신(TX) 핀과 수신(RX) 핀을 물리적으로 절단하여, **데이터가 OT 망에서 IT 망으로만 흐를 수 있고, IT 망에서 OT 망으로는 1비트의 데이터(악성코드 명령)도 거꾸로 들어오지 못하게 하는 하드웨어 기반 철벽 차단 기술.**
2. **OT 전용 DPI (Deep Packet Inspection) 및 이상 탐지 (IDS)**
   - 일반 방화벽은 웹(HTTP) 통신만 검사하지만, OT 환경은 Modbus, DNP3, OPC-UA 등 산업용 특수 프로토콜을 사용.
   - 스위치 미러(Mirror) 포트에 OT 전용 침입 탐지 장비(Nozomi, Claroty 등)를 연결하여, 네트워크 흐름을 엿듣다가(Passive) 비정상적인 "밸브를 열어라(Write)" 명령 패킷이 발생하면 관리자에게 즉각 알람 발송.
3. **매체 제어 키오스크 및 무결성 기반 안티바이러스**
   - 폐쇄망의 가장 큰 감염 루트인 'USB 및 외주 인력의 유지보수 노트북' 통제.
   - 유지보수 시 반드시 전용 보안 Kiosk를 거쳐 백신 검사를 마친 USB만 인가하며, 구형 OS PC에는 시그니처 기반 백신 대신 **화이트리스트(Application Control)** 솔루션을 설치하여 등록되지 않은 랜섬웨어의 프로세스 실행 자체를 OS 커널단에서 원천 차단(Lockdown).

### Ⅴ. 결론 및 실무적 판단 포인트
- 제조 및 산업 인프라의 CISO는 OT 보안을 IT 보안 부서에 일방적으로 맡기는 우를 범해서는 안 됩니다. 현장 공장장(Plant Manager)은 IT 부서가 보안 패치를 핑계로 라인을 세우려 하면 극렬히 반대합니다(Shadow OT 발생). OT 보안의 성공 여부는 IT 팀과 OT 엔지니어 팀 간의 크로스펑셔널(Cross-functional) 거버넌스 통합에 있습니다. IT/OT 망 융합 지점(IDMZ)에 대한 **네트워크 마이크로 세그멘테이션(Micro-segmentation) 아키텍처**를 강제하고, 공장 내 모든 제어 자산(PLC/HMI)의 가시성(Visibility)을 OT 전용 탐지 솔루션을 통해 100% 식별(Asset Discovery)해 내는 것만이, 소리 없이 퍼지는 랜섬웨어와 제로데이(0-day) 공격으로부터 수조 원 규모의 생산 라인을 지켜내는 생존의 필수 조건입니다.

### 💡 문제 유형별 목차 전환 포인트
- **[4차 산업 혁명 / 스마트 팩토리(IT-OT 융합) 환경의 보안 위협과 산업 제어 시스템 아키텍처 구축 방안]**: Ⅰ과 Ⅱ번(IT와 OT의 가용성 중심 패러다임 차이)을 전면에 세워, 왜 기존 범용 보안 솔루션이 공장에서는 맹독이 되는지 아키텍처적 한계를 증명.
- **[폐쇄망(Air-gap) 환경의 한계와 퍼듀 모델(Purdue Model) 기반 OT 망분리/망연계 기술 설계]**: Ⅲ번(계층적 퍼듀 모델)을 뼈대로 잡고 Ⅳ번(단방향 다이오드 및 DPI 기술)을 엮어, "연결성(스마트화)과 격리성(보안)이라는 상충되는 목표를 하드웨어/네트워크 분할 장비로 어떻게 동시에 충족시킬 것인가"에 대한 심화 엔지니어링 해법 전개.
