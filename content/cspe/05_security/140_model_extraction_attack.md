## Ⅰ. 개요
- **정의**: 대상 모델의 API를 반복 질의하여 동일한 기능을 재현하는 복제 모델을 구축하는 공격
- **배경/필요성**: 모델 학습에 투자된 비용·데이터가 API를 통해 간접적으로 탈취될 수 있어, 모델 자체가 보호 대상 자산임
- **비유**: 레스토랑 메뉴를 반복 주문·시식하여 레시피를 역추론하는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 지적재산 보호 | 모델 역전(139 참조)과의 차이: 데이터 복원 vs 모델 복제 | 추출된 모델로 후속 공격(적대적 예제 생성)이 가능함 |

> 요약: 모델 추출은 API 질의를 통해 대상 모델의 기능을 복제하는 지적재산 탈취 공격임

## Ⅱ. 구성요소
```text
Target Model API --> Query-Response Pairs
                          |
                          v
Attacker --> Substitute Model Training --> Clone Model
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Query-Response Pairs | 대상 모델에 보낸 입력과 수집한 출력의 쌍 | 문제-정답 데이터셋 |
| Substitute Model | 수집한 데이터로 학습시킨 복제 모델 | 모사품 |
| Transfer Attack | 복제 모델에서 생성한 적대적 예제를 원본에 적용하는 후속 공격 | 모조 열쇠로 원본 금고 개방 |

> 요약: 질의-응답 쌍을 수집하여 대리 모델을 학습시키는 구조임

## Ⅲ. 절차
```text
Query --> Collect --> Train --> Validate
```
- 1단계: Query — 대상 모델 API에 다양한 입력을 체계적으로 질의함
- 2단계: Collect — 입력-출력 쌍을 대규모로 수집하여 학습 데이터셋을 구성함
- 3단계: Train — 수집된 데이터셋으로 대리 모델을 학습시킴
- 4단계: Validate — 대리 모델의 정확도를 원본과 비교하여 복제 품질을 검증함

> 요약: 질의 → 수집 → 학습 → 검증의 4단계로 모델을 복제함

## Ⅳ. 문제점
- 저비용 복제: 수천~수만 건의 질의만으로 원본 모델의 90% 이상 정확도 복제가 가능함
- 지적재산 침해: 수억 원 규모의 학습 투자가 API 비용 수만 원으로 탈취될 수 있음
- 후속 공격 가능: 복제 모델을 이용하여 적대적 예제(143 참조)를 원본에도 전이 가능함

> 요약: 저비용 복제, 지적재산 침해, 후속 공격 전이가 주요 문제임

## Ⅴ. 개선방안
1. 단기: API 응답에 워터마크를 삽입하거나 출력 정밀도를 제한하여 복제 품질을 저하시킴
2. 중기: API 질의 빈도·패턴 분석으로 비정상 대량 질의를 탐지·차단하는 레이트 리미팅 적용
3. 장기: 모델 접근을 토큰 기반 인증·과금과 연계하여 대규모 질의의 경제적 장벽을 높임

> 요약: 출력 제한 → 질의 탐지 → 접근 과금으로 모델 자산을 보호함

## Ⅵ. 전망
- 발전 방향: LLM API 시장 확대로 모델 추출 위협이 SaaS 전반으로 확산 중
- 기술사적 판단: AI 모델을 영업비밀·저작물로 보호하는 법적 프레임워크가 정비될 것임
- 기술사 제언: API 보안 정책에 모델 추출 방어를 기본 항목으로 포함할 필요
