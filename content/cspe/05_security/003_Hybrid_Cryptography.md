## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 대칭 암호화의 속도와 비대칭 암호화의 키 관리 편의성을 결합한 암호화 방식임 |
| **배경/필요성** | 대량 데이터의 빠른 암호화와 안전한 키 분배를 동시에 만족시키기 위한 현실적 대안 필요 |
| **출제 의도** | 대칭/비대칭 암호의 장단점 상호 보완 기법 및 TLS/SSL 통신 과정 적용 사례 이해도 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Asymmetric Key   |      |  Symmetric Key    |      |  Bulk Data Enc    |
| (비밀키 안전 분배)|----->| (데이터 암호화용) |----->| (고속 데이터 전송)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **세션 키 (Session Key)** | 실제 데이터를 암호화/복호화하는 데 사용되는 일회성 대칭키임 | 편지를 봉인하는 스티커 |
| **비대칭 암호** | 세션 키를 안전하게 수신자에게 전달하기 위해 사용되는 암호 방식임 | 스티커를 안전하게 보낼 특수 금고 |
| **대칭 암호** | 세션 키를 통해 대용량 원본 데이터를 고속으로 암호화하는 방식임 | 편지 내용을 숨기는 암호펜 |

> 요약: 비대칭키로 일회성 세션 키를 분배하고, 그 세션 키(대칭키)로 데이터를 고속 암호화하는 구조임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 세션키 생성 |-->| 2. 세션키 암호 |-->| 3. 데이터 암호 |-->| 4. 전송 및 복호|
| (난수 기반)    |   | (수신자 공개키)|   | (세션키 이용)  |   | (세션키 추출)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **세션키 생성**: 송신자가 통신 세션에 사용할 일회성 대칭키(세션 키)를 난수로 생성함
2. **세션키 암호화**: 송신자가 수신자의 공개키를 이용해 생성한 세션 키를 암호화함
3. **데이터 암호화**: 송신자가 세션 키를 이용해 원본 데이터를 대칭 암호화함
4. **전송 및 복호화**: 암호화된 세션 키와 데이터를 전송하고, 수신자는 개인키로 세션 키를 복구 후 데이터를 복호화함

> 요약: 세션 키 생성 및 안전한 전달을 시작으로 데이터의 고속 암호화 통신을 달성함.

## Ⅳ. 문제점
* **난수 생성기의 취약성**: 난수 생성 로직이 취약할 경우 예측 가능한 세션 키가 생성되어 보안이 약화됨
* **PFS(완전 순방향 비밀성) 부재**: 과거의 세션 키가 유출될 경우, 해당 세션 키로 암호화된 이전 데이터까지 모두 해독됨
* **프로세스 오버헤드**: 세션 생성 시마다 비대칭 암호 연산이 필요하여 초기 핸드셰이크 지연 발생

## Ⅴ. 개선방안
* **단기 방안 (강력한 난수 사용)**: 하드웨어 기반 난수 생성기(TRNG)를 활용하여 세션 키의 엔트로피 강화
* **중기 방안 (PFS 도입 적용)**: DHE, ECDHE 등 세션마다 독립된 키를 생성하는 알고리즘을 도입해 완전 순방향 비밀성 보장
* **장기 방안 (핸드셰이크 최적화)**: TLS 1.3의 0-RTT/1-RTT 도입 등 세션 재개 기법을 통해 초기 연결 지연 최소화

## Ⅵ. 전망
* 현재 웹 통신(HTTPS)의 근간 기술로 자리잡았으며, 향후 PQC(양자내성암호)와의 결합(KEM)으로 발전할 전망임
* 하이브리드 키 교환 방식을 통해 레거시 시스템과 양자 시대 간 안전한 과도기를 제공할 것임
