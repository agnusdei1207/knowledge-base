## 미리 알고가기

- 4C는 Code, Container, Cluster, Cloud 네 계층을 뜻함
- 클라우드 네이티브는 코드 변경에서 배포까지가 빠르므로 한 지점만 지켜서는 빈틈이 남기 쉬움
- 상위 계층 경보만 보면 원인을 놓치기 쉬우므로 어느 계층에서 문제가 생겼는지 구분해야 함

## Ⅰ. 개요

- **정의/개념**: 클라우드 네이티브 보안 4C는 Code, Container, Cluster, Cloud 네 계층에 보안 통제를 배치하는 계층형 보호 모델임
- **배경/필요성**: 쿠버네티스 환경은 취약 코드, 잘못된 이미지, 느슨한 클러스터 정책, 과도 권한이 이어져 침해로 커짐. 계층별 책임 구분이 필요함

## Ⅱ. 특징

- 개발 단계부터 운영 단계까지 이어지는 보안 관점을 제공함
- 각 계층의 통제 목적이 달라 원인 파악과 조치 위치를 빠르게 정할 수 있음
- 하위 계층이 약하면 상위 계층 통제만으로는 피해를 막기 어려움
- 4개 계층을 따로 관리하면 예외가 누적되므로 공통 정책과 자동화가 중요함

## Ⅲ. 종류 및 비교

| 계층 | 주로 보는 대상 | 대표 통제 |
|:---|:---|:---|
| Code | 소스코드, 의존성, IaC | 시큐어 코딩, SAST, 비밀 탐지, IaC 점검 |
| Container | 이미지와 패키지 | 이미지 스캔, 서명 검증, 최소 베이스 이미지 |
| Cluster | 쿠버네티스 제어면과 워크로드 정책 | RBAC, Admission 제어, 네트워크 정책 |
| Cloud | 계정, 네트워크, 스토리지, IAM | CSPM, CIEM, 로그, 암호화, 보안 가드레일 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Code 계층 | 취약 코드와 잘못된 IaC와 노출된 비밀을 배포 전에 줄임 |
| Container 계층 | 이미지 취약점과 서명 상태를 확인해 불안전한 산출물 배포를 막음 |
| Cluster 계층 | 쿠버네티스 정책과 권한과 네트워크 경계를 관리함 |
| Cloud 계층 | 계정 설정, 스토리지 공개 범위, 클라우드 권한을 통제함 |

```text
Code -> Container -> Cluster -> Cloud
  |         |            |         |
사전 예방  배포 전 검증  정책 강제   운영 가드레일
```

## Ⅴ. 원리 및 절차 흐름도

```text
코드 작성 -> 이미지 빌드 -> 클러스터 배포 심사 -> 클라우드 운영 통제 -> 로그 기반 재점검
```

1. **코드 점검**: 취약 코드, 노출 비밀, 잘못된 IaC를 찾음
2. **이미지 점검**: 패키지 취약점과 서명 상태를 확인함
3. **배포 심사**: 클러스터 정책으로 위험한 매니페스트를 막음
4. **운영 통제**: 클라우드 계정, 네트워크, 스토리지, 권한을 관리함
5. **재점검**: 로그와 경보를 바탕으로 약한 계층을 다시 보강함

## Ⅵ. 실무 적용 및 유의점

1. 쿠버네티스 운영 조직은 코드 점검과 클러스터 정책을 함께 두고 계층별 치명 경보 수와 정책 위반 차단 배포 건수로 확인함
2. 팀마다 도구가 나뉘면 예외가 누적되므로 코드부터 클라우드까지 위험 등급을 맞추고 계층 간 중복 예외 수로 점검함

## Ⅶ. 결론

- 클라우드 네이티브 보안 4C는 어느 계층에서 무엇을 막아야 하는지 나누는 설계 틀이므로 계층 간 연결 운영이 핵심임
