# 📖 【암기용】 개념 완전 이해

> 목적: IAM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: IAM은 사람·서비스·기기 신원을 만들고, 인증하고, 권한을 부여하며, 사용 이력을 감사하는 관리 체계임
- **왜 필요한가**: 계정이 흩어지면 퇴사자 계정, 과다 권한, 공유 계정, 미인가 API 키가 남는다. IAM은 신원 수명주기를 통제해 침해 경로를 줄인다.
- **핵심 직관**: 회사의 인사 카드, 출입증, 업무 권한, 출입 기록을 하나의 절차로 묶는 보안 기반임

## 깊이 이해
- **배경·문제의식**: 클라우드와 SaaS가 늘면 계정 저장소가 AD, IdP, AWS IAM, GitHub, Kubernetes, DB로 분산된다. 수동 생성·삭제는 누락과 과다 권한을 만든다.
- **작동 원리**: HR 시스템에서 입사·이동·퇴사 이벤트가 발생하면 IGA가 계정을 생성·변경·회수한다. IdP는 SSO와 MFA로 인증하고, 각 서비스는 RBAC/ABAC/PBAC로 권한을 집행한다.
- **비유**: 사원증 발급부터 회의실 출입, 금고 접근, 퇴사 시 카드 회수까지 한 부서가 표준 절차로 운영하는 것과 같음
- **구체 예시**: 신입 개발자 입사 시 4시간 내 IdP 계정, Git 저장소 읽기 권한, Jira 프로젝트 권한을 자동 부여하고, 퇴사 시 15분 내 세션·토큰·API Key를 회수함
- **흔한 오해·주의점**: IAM은 로그인 화면만 의미하지 않는다. Joiner-Mover-Leaver, 권한 검토, 서비스 계정, 감사 로그까지 포함하는 운영 체계임

## 연결 개념
- SSO·MFA — IAM 인증 계층의 핵심 통제
- IGA (Identity Governance and Administration) — 계정 수명주기와 권한 검토
- PAM — 관리자·root·break-glass 계정의 별도 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: IAM은 인증 기술 문제가 아니라 신원 수명주기, 권한 부여, 감사, 규정 대응을 묶는 보안 운영 체계로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IAM은 디지털 신원 생성부터 인증, 인가, 권한 검토, 폐기까지 관리하는 접근 보안 기반이다.
> 2. **가치**: JML 프로세스와 SSO/MFA를 통해 퇴사자 계정, 공유 계정, 과다 권한을 줄이고 감사 증적을 확보한다.
> 3. **판단 포인트**: IdP, IGA, RBAC/ABAC, 로그·감사, 서비스 계정 관리를 하나의 흐름으로 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 신원 수명주기 통제 이해 확인 | Joiner-Mover-Leaver, 계정 생성·변경·회수 | 로그인·비밀번호 관리만 설명 |
| 인증·인가 분리 역량 확인 | SSO/MFA는 인증, RBAC/ABAC/PBAC는 인가 | 인증 성공을 권한 허용으로 오해 |
| 감사·컴플라이언스 운영 확인 | 권한 검토, 로그 보존, 휴면 계정 제거 | 클라우드·SaaS·서비스 계정 누락 |

> 요약: IAM 문제는 기술 요소 나열보다 계정 수명주기와 권한 감사 체계를 연결해야 한다.

## Ⅰ. 개요 및 필요성

IAM은 신원과 접근권한을 전사적으로 관리하는 보안 체계이다.
멀티클라우드와 SaaS 환경에서는 계정 저장소가 분산되어 퇴사자 계정, 과다 권한, 장기 토큰이 침해 원인이 된다.
IAM은 HR 이벤트 기반 계정 수명주기, SSO/MFA, 권한 검토, 로그 감사를 통해 접근 위험을 통제한다.

---

## Ⅱ. 구조 및 구성요소

```text
HR Source -> IGA -> IdP/Directory -> Application/Cloud
              |          |
              +-> Access Review
                         +-> MFA/SSO -> Audit Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| HR Source | 입사·이동·퇴사 기준 데이터 제공 | 사번, 부서, 직무, 고용 상태 |
| IGA | 계정 프로비저닝, 권한 요청·승인, 정기 검토 | SCIM, Workflow, SoD 룰 |
| IdP/Directory | 인증, SSO, MFA, 세션 관리 | SAML 2.0, OIDC, LDAP, AD |
| Resource System | 애플리케이션·클라우드·DB 권한 집행 | RBAC, ABAC, IAM Policy |
| Audit/SIEM | 로그인·권한 변경·실패 이벤트 분석 | 1년 이상 보존, UEBA 연계 |

> 요약: IAM은 HR 기준 데이터를 출발점으로 IGA, IdP, 자원 시스템, 감사 로그를 연결하는 수명주기 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
HR Event -> Identity Create/Change/Disable -> Authentication
-> Authorization -> Access Logging -> Periodic Review
-> Remediation
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입사·이동·퇴사 이벤트 수신 | HR-IAM 동기화 지연 p95 15분 이하 |
| 2 | 계정 생성·변경·잠금 자동 처리 | SCIM 성공률 99.5% 이상 |
| 3 | SSO와 MFA로 인증 수행 | MFA 적용률 98% 이상, Legacy Auth 0건 |
| 4 | 역할·속성·정책 기반 권한 부여 | 과다 권한 탐지 건수 월별 감소 |
| 5 | 로그 수집과 정기 권한 검토 | 고위험 권한 90일 주기 검토 |

> 요약: IAM은 HR 이벤트를 기준으로 계정을 자동 처리하고 인증·인가·감사를 순환 운영한다.

## Ⅳ. 특징

| 구분 | 개별 계정 관리 | IAM | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 계정 생성 | 시스템별 수동 등록 | HR 이벤트 기반 자동 프로비저닝 | 입사 후 4시간 이내 권한 부여 |
| 인증 | 서비스별 비밀번호 | SSO, MFA, FIDO2 | MFA 적용률 98% 이상 |
| 권한 관리 | 담당자 메일 승인 | 역할·속성·정책 기반 승인 | 고위험 권한 90일 검토 |
| 폐기 | 퇴사 후 수동 삭제 | 계정 잠금·토큰 회수 자동화 | 퇴사 후 15분 이내 비활성화 |

> 요약: IAM은 계정 생성부터 폐기까지 시간을 수치로 관리해 잔존 계정과 과다 권한을 통제한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 시스템별 계정 저장소 | 중앙 IdP+IGA+분산 집행 | SaaS 20개 이상 또는 클라우드 2개 이상 |
| 인증 | 비밀번호·VPN 중심 | SSO, MFA, FIDO2, Conditional Access | 관리자·원격접속 MFA 100% |
| 운영 | 수동 권한 신청 | Workflow, Access Review, SoD | 감사 지적 월 3건 이상이면 IGA 도입 |

> 요약: IAM은 서비스 수와 권한 복잡도가 증가할수록 중앙 신원과 분산 집행의 조합으로 전환해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 퇴사자 계정 잔존 | HR-IAM 연계 지연 | HR 이벤트 기반 자동 잠금, 세션 만료 | 비활성화 SLA 15분 |
| 과다 권한 | 부서 이동 후 권한 미회수 | Mover 프로세스, 90일 권한 검토 | Orphan entitlement 0건 |
| 서비스 계정 노출 | 장기 API Key 사용 | Secret Vault, 키 순환 90일, Workload Identity | 키 만료 초과 0건 |

> 요약: IAM의 주요 리스크는 사람 계정뿐 아니라 서비스 계정과 장기 토큰까지 포함해 관리해야 줄일 수 있다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 수명주기 | Joiner 4시간, Leaver 15분 이내 처리 | IGA Workflow 로그 |
| 인증 통제 | MFA 98% 이상, Legacy Protocol 0건 | IdP 리포트, Conditional Access |
| 감사 품질 | 고위험 권한 90일 주기 검토 완료율 100% | Access Review 결과, SIEM |

> 요약: IAM 성공 여부는 계정 처리 시간, MFA 적용률, 고위험 권한 검토 완료율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. HR을 권위 소스로 지정하고 SCIM으로 IdP, SaaS, 클라우드 계정을 자동 생성·잠금 처리
2. 관리자·원격접속·재무 시스템에 FIDO2 또는 TOTP MFA를 적용하고 Legacy Auth를 0건으로 차단
3. 고위험 권한은 90일, 일반 권한은 180일 주기로 Access Review를 수행하고 미응답 권한은 자동 회수

**결론 (2줄):**
- 기술사 판단: 서비스 수가 적으면 SSO/MFA부터, 감사·권한 복잡도가 크면 IGA와 PAM까지 단계적으로 도입함
- 향후 방향: 사람 신원 중심 IAM에서 Workload Identity, CI/CD 신원, API Key 거버넌스까지 범위가 확대됨
