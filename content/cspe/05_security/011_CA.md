## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 디지털 인증서를 발급, 갱신, 폐기하며 PKI 신뢰 사슬의 정점에 있는 공인/사설 인증 기관임 |
| **배경/필요성** | 인터넷상에서 통신 상대방의 공개키가 위조되지 않은 진짜임을 공신력 있게 입증해 줄 보증인 필요 |
| **출제 의도** | 계층적 인증 체계(Root CA, Sub CA)의 개념과 체인 오브 트러스트(Chain of Trust) 원리 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|     Root CA       |      | Intermediate CA   |      | End-Entity Cert   |
| (자체 서명 최상위)+----->| (권한 위임 중간CA)+----->| (최종 사용자 인증)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **Root CA (최상위 기관)** | 브라우저나 OS에 기본 내장되며, 스스로 자신의 신원을 보증(자체 서명)하는 최상위 기관임 | 국가 최고 행정부 |
| **Intermediate CA (중간 기관)** | 최상위 기관으로부터 인증 권한을 위임받아 최종 인증서를 발급하는 실무 기관임 | 지방 자치 단체 |
| **End-Entity (최종 사용자)** | 발급된 인증서를 실제 웹서버(TLS)나 이메일 암호화 용도로 사용하는 대상임 | 일반 시민 |

> 요약: 신뢰의 닻(Trust Anchor)인 Root CA에서 시작해 하위로 권한이 위임되는 트리 구조의 신뢰 사슬임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. CSR 생성    |-->| 2. 신원 및 소유|-->| 3. 서명 및 발급|-->| 4. 체인 설치   |
| (사용자가 요청)|   | (CA가 도메인확인)  | (중간CA 개인키)|   | (서버에 배치)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **CSR 생성**: 사용자가 자신의 개인키/공개키 쌍을 만들고, 공개키와 신원 정보를 포함한 인증서 발급 요청서(CSR)를 생성함
2. **도메인 및 신원 확인**: CA가 이메일, DNS 레코드, 서류 등을 통해 요청자가 해당 도메인이나 기업의 실제 소유자인지 엄격히 검증함
3. **서명 및 발급**: 심사가 통과되면 중간 CA가 자신의 개인키를 이용해 사용자의 공개키에 서명하여 인증서를 생성 발급함
4. **체인 설치**: 사용자는 발급된 인증서와 중간 CA 인증서를 함께 웹 서버 등에 설치하여 신뢰 사슬을 완성함

> 요약: 사용자 요청서(CSR) 접수 후 철저한 소유권 검증을 통해 상위 기관의 서명을 부여받는 생명주기임.

## Ⅳ. 문제점
* **부정 발급 위협**: CA 자체가 해킹되거나 사회공학적 공격을 당해 악성 공격자에게 가짜 인증서가 정상 발급될 위험 존재
* **신뢰 사슬 붕괴의 여파**: 하나의 Root CA가 탈취되면 이를 기반으로 한 수백만 개의 하위 인증서 전체가 즉각적 무효화됨
* **운영 통제 및 감사 부족**: 수많은 하위/사설 CA들이 동일한 발급 권한을 가지나, 보안 수준이 제각각이어서 취약점의 통로로 작용

## Ⅴ. 개선방안
* **단기 방안 (CAA 레코드 적용)**: DNS에 특정 CA만 인증서를 발급할 수 있도록 CAA 레코드를 설정하여 무단 발급 방지
* **중기 방안 (CT 로그 의무화)**: 모든 인증서 발급 내역을 공개된 투명성 로그(Certificate Transparency)에 기록하여 위변조 실시간 감시
* **장기 방안 (오프라인 Root CA)**: Root CA 시스템을 물리적으로 외부와 단절된 망에 분리 보관하고, 발급 작업 시에만 제한적 오프라인 운영 수행

## Ⅵ. 전망
* ACME 프로토콜(Let's Encrypt 등) 보급에 따라 도메인 검증(DV) 인증서 발급의 자동화가 더욱 가속화되고 있음
* 구글, 애플 등 주요 브라우저 및 OS 공급자가 CA 신뢰 목록을 매우 엄격하게 통제(Root Program 강화)하는 추세가 지속될 전망임
