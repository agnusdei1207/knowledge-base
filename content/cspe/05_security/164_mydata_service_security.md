## 미리 알고가기

- 마이데이터는 이용자 동의에 따라 여러 기관의 데이터를 한 서비스로 안전하게 옮겨 활용하는 체계임
- 접근 토큰은 전송 권한 범위와 유효 기간을 담아 연계 요청을 허용하는 인증 수단임
- 철회는 이용자가 이전에 허용한 전송과 활용 권한을 중단시키는 절차임

## Ⅰ. 개요

- **정의/개념**: 마이데이터 서비스 보안은 정보주체 동의에 따라 여러 기관 사이를 오가는 개인정보를 인증, 전송, 저장, 활용, 파기 전 단계에서 보호하는 통합 보안 체계임
- **배경/필요성**: 마이데이터는 데이터 이동을 전제로 하므로 한 번의 인증 오류나 과다 권한 설정만으로도 여러 기관 정보가 한꺼번에 노출될 수 있어 일반 웹 서비스보다 더 촘촘한 통제가 필요함

## Ⅱ. 특징

- 이용자 권한이 서비스 시작점이므로 본인 확인과 동의 범위 관리가 가장 중요함
- 송신자, 수신자, 중계 시스템이 함께 연결되므로 기관 간 신뢰 경계가 복잡함
- 데이터 전송 후에도 저장 기간, 재사용 범위, 철회 반영 상태를 계속 관리해야 함
- 연계 API가 많을수록 오남용 탐지와 감사 로그가 핵심 운영 수단이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 스크래핑 중심 연계 | 표준 연계 기반 마이데이터 |
|:---|:---|:---|
| 인증 방식 | 계정 위임이 과도해질 수 있음 | 범위와 기간을 제한한 토큰 기반 권한 관리가 가능함 |
| 데이터 통제 | 어떤 항목이 오가는지 세밀한 통제가 어려움 | 필드와 목적과 철회 범위를 세분화해 관리하기 좋음 |
| 장애 대응 | 화면 변경에 취약하고 추적이 어려움 | 표준 인터페이스와 로그로 장애 원인 분석이 쉬움 |
| 보안 핵심 | 계정 탈취 방지에 치우치기 쉬움 | 인증, 전송, 저장, 철회 전 단계를 함께 통제해야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이용자 인증과 동의 | 누구의 어떤 정보를 어떤 범위로 쓸지 정하는 출발점으로, 과도한 권한을 막는 핵심 통제임 |
| 정보전송자 연계 인터페이스 | 데이터를 내보내는 기관의 연계 지점으로, 요청 범위 검증과 응답 보호가 중요함 |
| 수신자 서비스 | 받은 정보를 보관하고 분석하는 주체로, 목적 외 이용과 장기 보관을 막아야 함 |
| 접근 토큰과 세션 관리 | 권한 범위와 만료 시간을 담아 재사용과 탈취 위험을 줄이는 인증 계층임 |
| 감사 로그와 이상 탐지 | 누가 언제 무엇을 요청했는지 남기고 비정상 패턴을 빠르게 찾아내는 운영 계층임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 이용자 인증    | -> | 권한 부여      | -> | 데이터 전송    | -> | 저장과 활용    |
+-------------+    +-------------+    +-------------+    +-------------+
       ^                                                    |
       +---------------- 철회와 감사 로그 관리 ----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 본인 확인      | -> | 동의 범위 설정 | -> | 연계 요청 검증 | -> | 암호화 전송    | -> | 활용 후 철회 관리 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **본인 확인**: 이용자의 신원을 확인하고 민감 기능에 강한 인증을 적용함
2. **동의 범위 설정**: 기관, 항목, 목적, 보유 기간, 제3자 제공 여부를 세분화함
3. **연계 요청 검증**: 송신자는 토큰 범위와 요청 항목이 맞는지 점검함
4. **암호화 전송**: 승인된 데이터만 보호된 통신 채널로 전달함
5. **활용 후 철회 관리**: 수신자는 목적 범위 안에서만 쓰고 철회되면 즉시 후속 처리함

## Ⅵ. 실무 적용 및 유의점

1. 마이데이터 사업자는 동의 범위를 토큰 권한과 정확히 연결해 과다 요청을 막고 초과 항목 차단 건수와 철회 반영 시간을 핵심 지표로 관리함
2. 기관 간 연계 인터페이스는 상호 인증과 변조 방지 로그를 기본으로 두고 인증 실패율과 비정상 전송량 탐지 건수로 이상 징후를 확인함

## Ⅶ. 결론

마이데이터 서비스 보안은 전송 구간만 지키는 문제가 아니라 동의와 권한과 저장과 철회를 하나의 흐름으로 묶어 관리하는 문제임.
