## 미리 알고가기

- DRP는 장애나 재해 뒤 IT 시스템과 데이터를 목표 수준으로 복구하기 위한 계획임
- RTO는 시스템을 복구해야 하는 목표 시간이고, RPO는 허용 가능한 데이터 손실 시점임
- 대체 사이트는 재해 시 서비스를 옮겨 운영하기 위한 예비 인프라 환경임

## Ⅰ. 개요

- **정의/개념**: DRP는 재해나 대규모 장애 발생 시 서버, 네트워크, 데이터, 애플리케이션을 정해진 RTO와 RPO 안에서 복구하기 위한 IT 복구 계획임
- **배경/필요성**: 백업이 있어도 절차와 우선순위와 전환 기준이 없으면 복구가 지연됨. 핵심 시스템을 어떤 순서로 살릴지 사전에 정해야 함

## Ⅱ. 특징

- 업무 연속성 중에서도 IT 인프라와 데이터 복구에 초점을 둠
- RTO와 RPO가 복구 전략과 백업 주기를 결정하는 핵심 기준임
- 복구 순서, 담당자, 명령어, 검증 절차가 구체적이어야 실제 장애 때 쓸 수 있음
- 정기 복구훈련 없이는 백업 성공과 서비스 복구 성공을 구분하기 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 콜드 사이트 | 웜 사이트 | 핫 사이트 |
|:---|:---|:---|:---|
| 준비 수준 | 장소와 기본 설비 중심 | 일부 장비와 데이터 준비 | 실시간 또는 근접 실시간 대기 |
| 복구 속도 | 느림 | 중간 | 빠름 |
| 비용 | 낮음 | 중간 | 높음 |
| 적합 업무 | 중요도 낮은 시스템 | 일반 업무 시스템 | 핵심 거래와 인증 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 복구 목표 | RTO와 RPO를 기준으로 시스템별 복구 수준과 우선순위를 정하는 기준임 |
| 백업과 복제 | 데이터 손실을 줄이기 위해 백업 주기와 원격 복제 방식을 정하는 기술 기반임 |
| 대체 인프라 | 재해 시 서비스를 이전할 데이터센터, 클라우드, 네트워크 환경임 |
| 복구 절차서 | 서버 기동, 데이터 복원, DNS 전환, 서비스 검증 순서를 담은 실행 문서임 |
| 복구 훈련 | 실제 복구 가능성과 소요 시간을 검증해 절차를 보완하는 활동임 |

```text
-------------+    +-------------+    +-------------+    +-------------+
| 장애 선언      | -> | 대체 환경 전환 | -> | 데이터 복구    | -> | 서비스 검증    |
+-------------+    +-------------+    +-------------+    +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
영향 확인 -> 재해 선언 -> 복구팀 소집 -> 인프라 전환 -> 데이터 복원 -> 서비스 확인
```

1. **영향 확인**: 장애 범위와 업무 영향을 파악해 재해 선언 여부를 판단함
2. **복구팀 소집**: 담당자와 협력사와 의사결정자를 즉시 연결함
3. **인프라 전환**: 대체 사이트나 클라우드 복구 환경으로 서비스를 옮김
4. **데이터 복원**: 백업과 복제본을 기준으로 목표 시점까지 데이터를 복구함
5. **서비스 확인**: 기능, 성능, 무결성을 확인한 뒤 정상 운영 전환을 승인함

## Ⅵ. 실무 적용 및 유의점

1. 결제와 인증 시스템은 RTO와 RPO를 업무 손실 기준으로 정하고 복구훈련 실제 소요 시간과 데이터 손실량으로 목표 달성 여부를 확인함
2. 클라우드 DR은 리전 전환만 믿지 말고 네트워크, 권한, 외부 연계까지 함께 시험하며 전환 실패 건수와 수동 조치 시간을 줄여야 함

## Ⅶ. 결론

- DRP는 백업 보유 여부가 아니라 목표 시간과 목표 시점 안에 서비스를 실제로 되살릴 수 있는지를 검증하는 계획임
