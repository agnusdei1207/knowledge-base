# 📖 【암기용】 개념 완전 이해

> 목적: 개인정보보호법의 수집·이용·제공·파기 원칙을 처음 보는 사람도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 개인정보 생애주기를 법적 근거와 목적 범위로 통제하는 기본법
- **왜 필요한가**: 회원가입, 로그, 결제, 상담, 마케팅 데이터는 목적 없이 모으면 유출·오남용·과징금으로 이어진다. 법은 "왜 모았는지, 어디까지 쓸지, 언제 지울지"를 처리자가 입증하게 함.
- **핵심 직관**: 개인정보는 회사 자산이 아니라 정보주체가 맡긴 물건이며, 맡긴 목적이 끝나면 되돌리거나 폐기해야 함.

## 깊이 이해
- **배경·문제의식**: 디지털 서비스는 식별자, 위치, 접속기록, 구매내역을 지속 수집한다. 동의 화면만 만들어도 목적 외 이용, 과다 수집, 보존기간 초과가 발생하면 제15조·제17조·제21조 위반이 됨.
- **작동 원리**: 제15조는 수집·이용 근거, 제16조는 최소 수집과 입증책임, 제17조는 제3자 제공 요건, 제18조는 목적 외 이용·제공 제한, 제21조는 보유기간 경과·목적 달성 시 파기를 규정함.
- **비유**: 택배 접수 때 주소를 받는 것은 배송 목적에 한정된다. 배송이 끝난 뒤 광고 문자에 쓰려면 별도 근거가 필요하고, 보존기간이 끝나면 송장을 폐기해야 함.
- **구체 예시**: 쇼핑몰은 주문 이행에 이름·주소·연락처를 수집할 수 있으나, 광고성 문자 발송은 별도 동의와 수신거부 이력 관리가 필요함. 계약·세법상 보존자료는 운영 DB와 분리 저장함.
- **흔한 오해·주의점**: 동의가 있으면 모든 처리가 허용되는 것은 아님. 최소 수집, 목적 제한, 안전조치, 파기, 처리방침 공개는 동의와 별개로 확인됨.

## 연결 개념
- 개인정보 영향평가: 대규모 개인정보파일 도입 전 침해요인 분석
- ISMS-P: 관리체계와 개인정보 처리단계 통제의 인증 기준
- 가명정보: 통계·연구 목적 처리 시 재식별 금지와 안전조치 필요

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 조문 암기가 아니라 처리 생애주기별 법적 근거, 입증자료, 감사 지표를 연결해 답안을 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 개인정보보호법은 수집·이용·제공·파기 전 단계에서 목적 제한과 최소 수집을 요구하는 생애주기 통제법이다.
> 2. **가치**: 제15조·제17조·제21조를 처리 흐름에 매핑하면 동의 누락, 목적 외 제공, 보존기간 초과를 감사로그로 검증할 수 있다.
> 3. **판단 포인트**: 수집 근거, 제공 대상, 보존기간, 파기 증적을 서비스·DB·로그 단위로 남기지 못하면 위반 판단에서 처리자가 입증 실패함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개인정보 생애주기 통제 이해 확인 | 제15조 수집·이용, 제16조 최소 수집, 제17조 제공, 제21조 파기 | 동의만 쓰고 계약·법령·정당한 이익 근거 누락 |
| 보안 운영 관점 확인 | 처리목적, 항목, 보유기간, 파기증명서, 접근로그 1년 이상 보관 | 조문 나열 후 시스템 통제·감사 지표 누락 |
| 침해 대응 판단 확인 | 유출 인지 후 72시간 내 통지·신고, 영향범위 산정 | 사고 후 통지와 평시 파기 절차 혼동 |

> 요약: 개인정보보호법 답안은 조문명보다 처리단계별 근거와 입증자료를 연결해야 점수를 확보함.

---

## Ⅰ. 개요 및 필요성

- 개요: 개인정보 처리 전 과정 기본법
- 배경: 개인정보처리자는 수집 목적, 항목, 보유기간, 제공 대상, 파기 절차를 사전에 정하고 처리 후 증적을 남겨야 한다.
- 필요성: 2025.10.2 시행 법령 기준으로 최소 수집 입증책임, 파기·분리보관, 처리방침 공개를 감사 증적으로 관리해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
정보주체/서비스 요구 -> 수집 근거 판단 -> 이용 목적 제한 -> 제3자 제공 통제 -> 보유기간 관리 -> 파기/분리보관
                         +-> 동의/계약/법령 근거 기록
                         +-> 접근권한/암호화/로그 감사
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 수집·이용 근거 | 제15조에 따라 동의, 계약, 법령, 생명·재산 보호, 정당한 이익 판단 | 동의 시 목적·항목·보유기간·거부권 고지 |
| 최소 수집 | 제16조에 따라 목적 달성에 필요한 항목만 수집 | 최소 수집 입증책임은 처리자 부담 |
| 제3자 제공 | 제17조에 따라 제공받는 자, 목적, 항목, 보유기간 고지 | 목적 외 제공은 제18조 예외 요건 별도 검토 |
| 파기·분리보관 | 제21조에 따라 불필요 시 지체 없이 파기 | 법령 보존자료는 운영 데이터와 분리 저장 |

> 요약: 개인정보보호법 구조는 수집 근거, 목적 제한, 제공 통제, 파기 증적을 하나의 생애주기로 묶는 방식임.

---

## Ⅲ. 동작원리 및 흐름도

```text
처리 목적 정의 -> 법적 근거 선택 -> 고지/동의 또는 계약 처리 -> DB 저장/접근통제 -> 제공 심사 -> 보존기간 만료 -> 파기 증적 생성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 개인정보 처리 목적·항목·보유기간 정의 | 처리방침, 데이터 맵, ROPA |
| 2 | 제15조 근거와 제22조 동의 구분 적용 | 동의 로그, 계약서, 법령 근거표 |
| 3 | 이용·제공 시 목적 범위와 제3자 제공 항목 심사 | 제공대장, API 호출 로그, 수탁자 목록 |
| 4 | 보유기간 경과·목적 달성 시 파기 또는 분리보관 | 파기대장, 삭제 배치 결과, 백업 만료 정책 |

> 요약: 개인정보 처리는 목적 정의에서 시작해 보유기간 만료 후 파기 증적 생성까지 이어지는 통제 프로세스임.

## Ⅳ. 특징

| 구분 | 기존 관행 | 개인정보보호법 기준 | 수치·조항 |
|:---|:---|:---|:---|
| 수집 | 서비스 편의상 과다 항목 수집 | 목적 필요 최소 항목만 수집 | 제16조, 입증책임 처리자 |
| 이용 | 동의 화면 하나로 다목적 이용 | 수집 목적 범위 내 이용, 추가 이용은 합리적 관련성 검토 | 제15조, 시행령 제14조의2 |
| 제공 | 제휴사 일괄 제공 | 제공받는 자·목적·항목·기간 고지 | 제17조, 제18조 |
| 파기 | 휴면·탈퇴 데이터 장기 보관 | 불필요 시 지체 없이 파기, 법령 보존자료 분리 | 제21조 |

> 요약: 개인정보보호법의 차이는 동의 보유가 아니라 목적·항목·기간·제공·파기별 입증자료 보유에 있음.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 개인정보보호법 기반 운영 | 선택 기준 |
|:---|:---|:---|:---|
| 수집 설계 | 화면별 동의문 관리 | 데이터 항목별 목적·근거·보유기간 매핑 | 신규 항목 추가 시 DPIA 또는 사전 검토 |
| 제공 통제 | 제휴 API 단순 연동 | 제공대장, 수탁자 관리, 국외 이전 고지 | 제공 목적·수신자·기간 변경 시 재동의 판단 |
| 파기 운영 | 탈퇴 DB 수동 삭제 | 주기 배치, 백업 만료, 파기증명서 자동 생성 | 파기 누락률 0건, 보존 예외 사유 기록 |

> 요약: 실무 적용은 동의 UI보다 데이터 맵, 제공대장, 파기대장의 일치 여부로 판단함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과다 수집 | 필수·선택 항목 미분리 | 가입 폼 필수 항목 10개 이하 검토, 선택동의 분리 | 필수항목 거절률, 선택동의 철회율 |
| 목적 외 제공 | 제휴 API 목적 변경 미심사 | 제공 전 법무·보안 체크리스트, API scope 제한 | 미승인 제공 0건, 제공대장 월 1회 점검 |
| 파기 누락 | 백업·로그 보존기간 미정의 | TTL, WORM 로그 예외, 백업 보존 30~90일 정책 | 만료 데이터 잔존 0건, 삭제 실패 재처리율 |

> 요약: 주요 리스크는 과다 수집, 목적 외 제공, 파기 누락이며 데이터 흐름별 증적으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 법적 근거 커버리지 | 개인정보 테이블 100% 목적·근거·기간 등록 | 데이터 카탈로그, ROPA 대조 |
| 제공·위탁 통제 | 제3자 제공·위탁 계약 100% 대장 등록 | API 목록, 계약서, 제공 로그 샘플링 |
| 파기·사고 대응 | 파기 실패 0건, 유출 인지 후 72시간 내 통지·신고 | 파기 배치 리포트, 사고 대응 타임라인 |

> 요약: 성공 여부는 처리근거 등록률, 제공대장 정합성, 파기 실패 건수, 72시간 신고 준수로 판정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 개인정보 데이터 맵 작성: 테이블·컬럼별 목적, 제15조 근거, 보유기간, 파기 방식, 책임부서 100% 등록
2. 제공·위탁 통제: 제3자 제공 API는 수신자·목적·항목·기간을 제공대장에 기록하고 OAuth scope와 IP allowlist 적용
3. 파기 자동화: 보유기간 만료 배치, 백업 만료 정책, 파기대장 전자서명으로 월 1회 잔존 데이터 0건 점검

**결론 (2줄):**
- 기술사 판단: 계약 이행 데이터는 제15조제1항제4호, 마케팅·제3자 제공은 별도 동의와 철회 절차를 선택함
- 향후 방향: 개인정보 처리는 동의 관리에서 데이터 카탈로그·ROPA·파기 자동화 기반의 상시 감사 체계로 전환 필요
