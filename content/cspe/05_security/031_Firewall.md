## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 내부망과 외부망(인터넷) 사이에서 트래픽을 허용하거나 차단하는 보안 접근 통제 시스템임 |
| **배경/필요성** | 신뢰할 수 없는 외부 네트워크로부터의 무분별한 침입을 방어할 1차적인 네트워크 출입문 필요 |
| **출제 의도** | 1세대(패킷 필터링), 2세대(상태 기반), 3세대(애플리케이션 계층) 방화벽의 기술 진화 단계 파악 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
| Packet Filtering  |      | Stateful Inspect. |      | App. Layer (NGFW) |
| (L3/L4 포트 제어) +----->| (연결 상태 추적)  +----->| (L7 내용/앱 검사) |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **패킷 필터링 (1세대)** | IP 주소와 포트 번호(L3/L4)만 보고 단순히 허용/차단을 결정하는 기본 방식임 | 방문자의 신분증과 목적지만 확인하는 초소 경비 |
| **상태 기반 검사 (2세대)** | TCP 세션의 연결 상태(State Table)를 기억해, 성립된 통신의 후속 패킷을 지능적으로 처리함 | 출입 명부를 보고 나갔다 들어오는 사람 확인 |
| **응용 계층 방화벽 (3세대)**| 패킷의 내용(Payload, L7)까지 뜯어보고 특정 애플리케이션이나 악성코드 여부를 식별함 | 가방을 열어 위험물질이나 특정 물건을 검사 |

> 요약: 포트 번호 확인에서 시작하여 통신 맥락(세션)을 이해하고, 최종적으로 데이터 내용까지 검사하는 방향으로 진화함.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 패킷 수신   |-->| 2. 룰셋 매칭   |-->| 3. 세션/페이로드|-->| 4. 허용/차단   |
| (외부망 유입)  |   | (정책 기반 검사)|   | (심층 상태 검열)|   | (Drop/Accept)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **패킷 수신**: 외부(인터넷) 또는 다른 구역에서 유입되는 트래픽 패킷을 방화벽 인터페이스가 가로챔
2. **룰셋 매칭**: 관리자가 설정한 접근 통제 정책(ACL: IP, 포트)을 최상단 룰부터 순차적으로 비교함
3. **세션 및 페이로드 분석(SPI/DPI)**: 기존에 맺어진 세션 테이블을 조회하고, 필요 시 패킷 본문(Payload)의 애플리케이션 서명까지 깊이 파악함
4. **허용/차단 수행**: 정책에 부합하면 내부망으로 패킷을 통과(Accept)시키고, 위반 시 폐기(Drop/Reject) 후 로그를 남김

> 요약: 미리 정의된 룰셋과 동적인 세션 테이블을 교차 검증하여 트래픽의 생사(통과 여부)를 결정함.

## Ⅳ. 문제점
* **암호화된 트래픽(TLS) 맹점**: 최신 웹 트래픽의 90% 이상이 암호화되어 있어, 방화벽이 패킷 내부(L7) 내용을 검사하지 못하고 무조건 통과시킴
* **단순 포트 우회 공격 증가**: 공격자가 정상 포트(예: HTTP 80, HTTPS 443)로 악성코드나 비정상 앱 데이터를 터널링하여 필터링 우회
* **내부자 위협 무방비(경계 보안 한계)**: 방화벽은 외곽 경계만 방어하므로, 이미 내부망에 침투한 악성코드나 악의적 내부자의 횡적 이동(Lateral Movement)을 막을 수 없음

## Ⅴ. 개선방안
* **단기 방안 (SSL 복호화 가시성)**: 방화벽에 SSL/TLS 가시성 장비 기능을 활성화(SSL Inspection)하여 암호화된 트래픽을 복호화 후 심층 검사(DPI) 수행
* **중기 방안 (NGFW 전면 도입)**: 단순 포트 제어가 아닌, 사용자 ID와 애플리케이션 시그니처 기반으로 정밀 차단하는 차세대 방화벽(NGFW)으로 마이그레이션
* **장기 방안 (제로 트러스트 및 마이크로 세그멘테이션)**: 경계 기반 방어를 탈피하여 서버 간 트래픽(East-West)도 각각 통제하는 마이크로 세그멘테이션(SDN 기반 제어) 도입

## Ⅵ. 전망
* 단순 네트워크 장비에서 벗어나 IPS, 안티바이러스, 웹 필터링, 샌드박스가 통합된 통합 위협 관리(UTM) 형태로 기본 진화 완료함
* 하드웨어 어플라이언스의 한계를 넘어, 클라우드 환경 보호를 위한 가상 방화벽(vFW) 및 SASE(보안 서비스 엣지) 아키텍처의 핵심 클라우드 네이티브 요소로 융합 중임
