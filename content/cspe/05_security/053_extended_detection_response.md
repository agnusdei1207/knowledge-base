## 미리 알고가기

- XDR은 엔드포인트, 네트워크, 이메일, 클라우드 텔레메트리를 통합해 사건 단위로 탐지·대응하는 플랫폼임
- 여러 도메인을 묶는다는 점에서 단일 센서형 제품과 다르고 SIEM보다 실행 중심성이 강함
- 벤더 통합 범위와 오픈 연동 수준이 실제 활용도를 좌우함

## Ⅰ. 개요

- **정의/개념**: XDR은 엔드포인트, 네트워크, 이메일, 클라우드, ID 영역의 보안 텔레메트리를 통합 상관분석해 공격 경로를 사건 단위로 재구성하고 탐지와 대응을 자동화하는 확장형 보안 플랫폼임
- **배경/필요성**: 공격이 여러 보안 도메인을 넘나들지만 EDR, NDR, 이메일 보안, SIEM이 각각 분리되면 공격 전후 맥락을 잃기 쉬워 다계층 텔레메트리를 하나의 사건 흐름으로 묶을 체계가 필요함

## Ⅱ. 특징

- 여러 보안 도메인의 이벤트를 단일 사건으로 묶어 분석가의 triage 부담을 줄일 수 있음
- 경보 중심이 아니라 자산, 계정, 프로세스, 통신을 하나의 스토리로 연결해 분석함
- 탐지와 대응이 한 플랫폼 안에서 이어져 SOAR와 유사한 자동화 효과를 일부 흡수할 수 있음
- 벤더 종속과 데이터 정규화 품질 문제를 해결하지 못하면 통합보다는 새로운 사일로가 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | EDR | NDR | XDR |
|:---|:---|:---|:---|
| 주 데이터 | 엔드포인트 행위 | 네트워크 행위 | 다계층 텔레메트리 |
| 강점 | 단말 내부 가시성 | 동서 트래픽과 C2 | 사건 단위 상관분석 |
| 대응 범위 | 단말 중심 | 네트워크 중심 | 다중 도메인 연계 |
| 대표 한계 | 단말 밖 맥락 부족 | 단말 행위 상세 부족 | 통합 품질과 종속성 부담 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Multi-domain Telemetry | EDR, NDR, 이메일, IAM, 클라우드 로그를 수집하는 입력 계층으로 데이터 폭이 넓을수록 상관 가치가 커짐 |
| Normalization and Entity Graph | 사용자, 단말, 프로세스, 세션을 공통 엔티티로 연결하는 정규화 계층으로 사건 재구성의 핵심임 |
| Correlation and Detection | 여러 도메인의 이벤트를 묶어 단일 사건으로 판단하는 분석 계층임 |
| Response Orchestration | 격리, 차단, 계정 잠금, 티켓 생성 같은 조치를 자동 수행하는 대응 계층임 |
| Analyst Workspace | 사건 타임라인과 근거와 조치 이력을 보여주는 운영 계층임 |

```text
+---------------+    +----------------+    +----------------+    +----------------+
| Multi-domain  | -> | Entity Graph   | -> | Detection      | -> | Response       |
| Telemetry     |    | / Normalize    |    | / Correlation  |    | / Case         |
+---------------+    +----------------+    +----------------+    +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 다계층 수집    | -> | 엔티티 정규화   | -> | 사건 상관분석   | -> | 대응 실행      | -> | 결과 환류      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **다계층 수집**: 여러 보안 도메인 텔레메트리를 수집함
2. **엔티티 정규화**: 사용자와 자산과 프로세스를 공통 기준으로 맞춤
3. **사건 상관분석**: 관련 이벤트를 연결해 공격 경로를 재구성함
4. **대응 실행**: 도메인별 조치를 자동 또는 반자동으로 수행함
5. **결과 환류**: 룰과 플레이북과 탐지 모델을 보완함

## Ⅵ. 실무 적용 및 유의점

1. 보안 도구가 많은 대기업 SOC는 XDR로 사건 단위 시야를 확보하기 좋지만 벤더별 스키마 차이와 중복 경보가 크므로 공통 엔티티 모델과 우선순위 룰을 먼저 정하고 사건 통합률과 분석가 triage 시간과 중복 경보 감소율로 확인함
2. 단일 벤더 XDR은 구축이 빠르지만 타사 장비 연동이 약하면 핵심 자산이 빠질 수 있으므로 open XDR 지원 범위와 API 연동 계획을 검토하고 연계 가능한 데이터 소스 수와 비가시 자산 비율로 확인함

## Ⅶ. 결론

- XDR은 여러 탐지 도메인을 하나의 사건으로 묶는 플랫폼이므로 수집 범위와 엔티티 정규화 품질과 연동 개방성이 확보될 때 실질적인 운영 효율을 만든다
