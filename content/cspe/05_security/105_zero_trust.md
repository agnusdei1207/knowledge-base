## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 네트워크 위치와 무관하게 모든 접근 요청을 신뢰하지 않고, 매 요청마다 신원·디바이스·컨텍스트를 검증하는 보안 아키텍처임 |
| **배경/필요성** | 경계 기반 보안(Perimeter Security)은 내부 침입·원격근무·클라우드 확산으로 무력화되어, 신뢰 없는(Never Trust) 모델이 필요함 |
| **출제 의도** | ZTA의 NIST SP 800-207 핵심 원칙과 구현 요소를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 정책엔진  | --> | 정책관리자| --> | 정책집행  |
| (PE)     |     | (PA)     |     | (PEP)    |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 정책 엔진(PE) | 신원·디바이스·행위·위협 인텔리전스를 종합하여 신뢰 수준(Trust Score)을 산출함 | 입국 심사 판정관 |
| 정책 관리자(PA) | PE의 결정에 따라 세션 수립·종료를 관리함 | 출입문 관리 시스템 |
| 정책 집행점(PEP) | 실제 트래픽 경로에서 접근을 허용·차단하는 게이트웨이·프록시임 | 출입문 차단봉 |

> 요약: PE(신뢰 판단) → PA(세션 관리) → PEP(접근 집행)으로 매 요청을 검증하는 아키텍처임.

## Ⅲ. 절차
```
+------------+     +------------+
| 접근요청   | --> | 신원·장치  |
| (사용자)   |     | 검증       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 세션발급   | <-- | 리스크    |
| 최소권한   |     | 점수산출   |
+------------+     +------------+
```

1. 접근 요청: 사용자·서비스가 리소스에 접근을 요청함(내부·외부 구분 없음)
2. 신원·장치 검증: IdP로 신원을 인증하고, EDR·MDM으로 디바이스 보안 상태를 확인함
3. 리스크 점수 산출: 접속 위치·시간·행위 패턴·위협 인텔리전스를 종합하여 Trust Score를 계산함
4. 최소 권한 세션 발급: Trust Score에 따라 필요한 최소 리소스에만 제한된 시간 동안 접근을 허용함

> 요약: 요청 → 검증 → 리스크 평가 → 최소 권한 발급으로 매 접근을 동적 통제함.

## Ⅳ. 문제점
- 구현 복잡성: 기존 경계 보안 인프라를 ZTA로 전환하는 데 장기간·고비용이 소요됨
- 레거시 호환: ZTA 미지원 레거시 시스템에 정책을 적용하기 어려움
- 사용자 마찰: 매 접근 시 추가 검증으로 업무 생산성이 저하될 수 있음

## Ⅴ. 개선방안
- (단기) 단계적 전환: 고위험 리소스부터 ZTA를 적용하고 점진적으로 확대함
- (중기) SASE 통합: 네트워크 보안과 ZTA를 SASE 프레임워크로 통합하여 구현 복잡성을 줄임
- (장기) AI 기반 연속 인증: 행위 분석 AI로 사용자 마찰 없이 연속적으로 신뢰를 평가함

## Ⅵ. 전망
- NIST SP 800-207 기반 ZTA가 공공·금융 부문 필수 아키텍처로 의무화되며, SASE·SSE와 결합한 클라우드 네이티브 ZTA가 차세대 보안 패러다임이 될 전망임
