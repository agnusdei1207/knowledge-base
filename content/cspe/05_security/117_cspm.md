## 미리 알고가기

- 오설정은 외부 공개 저장소, 과도한 보안 그룹 개방, 과한 권한처럼 잘못된 클라우드 설정을 말함
- 보안 기준은 CIS Benchmark처럼 설정의 적정 여부를 판단하는 점검 기준임
- 드리프트는 설계서나 IaC 코드와 실제 운영 설정이 시간이 지나며 달라지는 현상임

## Ⅰ. 개요

- **정의/개념**: CSPM은 클라우드 계정과 리소스 설정을 계속 수집해 보안 기준 위반과 위험 노출을 찾고 교정까지 연결하는 형상 관리 체계임
- **배경/필요성**: 클라우드는 클릭 한 번으로 설정이 바뀌고 계정과 리전도 빠르게 늘어나므로 수동 점검만으로는 퍼블릭 노출과 과도 권한을 제때 잡기 어려움

## Ⅱ. 특징

- 멀티 계정과 멀티 리전의 설정 상태를 한곳에서 계속 점검함
- 보안 그룹, 스토리지 공개 범위, 암호화, 로깅 같은 기준을 규칙으로 자동 평가함
- IaC와 연계하면 운영 이전과 운영 이후의 설정 오류를 함께 줄일 수 있음
- 자산 소유자와 태그 정보가 부정확하면 우선순위가 흔들리므로 자산 정합성이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정기 수동 점검 | CSPM |
|:---|:---|:---|
| 점검 주기 | 월간·분기 단위가 많음 | 설정 변경에 맞춰 지속 점검함 |
| 범위 | 담당자가 보는 계정과 서비스에 치우치기 쉬움 | 멀티 클라우드와 멀티 계정을 한 번에 다룸 |
| 조치 속도 | 탐지와 수정이 분리되기 쉬움 | 탐지 후 자동 교정이나 티켓 연계가 쉬움 |
| 적합 환경 | 소규모 단일 계정 | 빠르게 바뀌는 클라우드 운영 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 설정 수집기 | CSP API로 네트워크, IAM, 스토리지, 로그 설정을 수집함 |
| 규칙 엔진 | 보안 기준과 정책을 기준으로 위반 여부를 판단함 |
| 위험 우선순위화 | 외부 노출 여부, 자산 중요도, 연관 권한을 반영해 순서를 정함 |
| 조치 연계 | 자동 교정, 티켓 발행, IaC 수정 요청으로 후속 조치를 연결함 |
| 대시보드 | 계정별 위반 현황과 장기 추세를 보여줌 |

```text
클라우드 설정 수집 -> 정책 규칙 평가 -> 고위험 오설정 선별 -> 자동 교정/티켓 발행 -> 재점검
```

## Ⅴ. 원리 및 절차 흐름도

```text
계정 연결 -> 리소스 설정 수집 -> 기준 위반 탐지 -> 위험도 산정 -> 수정 또는 예외 처리 -> 재평가
```

1. **계정 연결**: 클라우드 계정과 리전을 CSPM에 연결함
2. **설정 수집**: 네트워크, 스토리지, IAM, 로깅 설정을 모음
3. **위반 탐지**: 보안 기준과 대조해 공개 노출과 누락 설정을 찾음
4. **위험도 산정**: 외부 노출 여부와 자산 중요도로 우선순위를 정함
5. **수정과 재평가**: 자동 교정이나 IaC 수정을 반영하고 다시 점검함

## Ⅵ. 실무 적용 및 유의점

1. 멀티 계정 클라우드에서는 외부 공개 저장소와 과도하게 열린 보안 그룹을 먼저 줄이고 외부 공개 자산 수와 암호화 미적용 리소스 수와 수정 완료 시간으로 확인함
2. 태그와 자산 소유자가 부정확하면 알림만 쌓이므로 IaC 저장소와 운영 계정을 연결해 책임 주체를 맞추고 장기 미조치 건수와 예외 승인 잔량으로 점검함

## Ⅶ. 결론

- CSPM은 설정 오류를 한 번 찾고 끝내는 도구가 아니라 바뀌는 클라우드 형상을 계속 따라가며 위험을 줄이는 운영 체계이므로 자산 정합성과 자동 교정 연계가 함께 갖춰져야 함
