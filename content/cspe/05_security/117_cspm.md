## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 클라우드 인프라의 보안 설정을 지속적으로 점검하여 오설정(Misconfiguration)을 자동 탐지·교정하는 보안 관리 도구임 |
| **배경/필요성** | 클라우드 보안 사고의 80%가 오설정에서 기인하며(Gartner), S3 퍼블릭 노출·보안 그룹 오픈 등 설정 오류의 자동 탐지가 필수임 |
| **출제 의도** | CSPM의 탐지 메커니즘과 CIS Benchmark·규제 프레임워크와의 관계를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 설정수집  | --> | 규칙평가  | --> | 자동교정  |
| (API스캔) |     | (Benchmark)|   | (Remediate)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 설정 수집 | CSP API를 통해 리소스 설정(IAM·네트워크·스토리지)을 주기적으로 수집함 | 건물 안전 점검 순찰 |
| 규칙 평가 | CIS Benchmark·PCI-DSS·ISMS-P 등 표준과 대조하여 위반을 탐지함 | 안전 기준 체크리스트 대조 |
| 자동 교정 | 탐지된 오설정을 IaC·Lambda·자동 실행으로 즉시 교정함 | 발견된 소화기 미비 즉시 보충 |

> 요약: 설정 수집 → 규칙 평가 → 자동 교정으로 클라우드 오설정을 지속적으로 관리함.

## Ⅲ. 절차
```
+------------+     +------------+
| CSP API    | --> | 설정스냅샷  |
| 연동       |     | 수집       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 대시보드   | <-- | 규칙대조  |
| 알림·교정  |     | 위반탐지   |
+------------+     +------------+
```

1. CSP API 연동: AWS·Azure·GCP의 API를 통해 CSPM이 클라우드 계정에 읽기 접근을 설정함
2. 설정 스냅샷 수집: IAM 정책·보안 그룹·스토리지 ACL·암호화 설정 등을 주기적으로 수집함
3. 규칙 대조·위반 탐지: 300+ 항목의 보안 규칙과 대조하여 위반(Critical~Low)을 분류함
4. 알림·자동 교정: 위반 항목을 대시보드·Slack에 알리고, 사전 정의된 교정 스크립트를 자동 실행함

> 요약: API 연동 → 수집 → 규칙 대조 → 알림·교정으로 오설정을 지속 관리함.

## Ⅳ. 문제점
- 오탐 과다: 엄격한 규칙이 비즈니스 맥락을 고려하지 못해 불필요한 알림이 다수 발생함
- 멀티 클라우드 정규화: CSP마다 리소스 모델이 달라 통합 분석·비교가 어려움
- 자동 교정 리스크: 자동 교정이 운영 서비스에 영향을 주어 장애를 유발할 수 있음

## Ⅴ. 개선방안
- (단기) 리스크 우선순위: 자산 중요도·노출 범위를 고려한 리스크 기반 우선순위로 알림 피로를 줄임
- (중기) IaC 스캔 통합: Terraform·CloudFormation 템플릿을 배포 전 스캔하여 오설정을 사전 차단함
- (장기) CNAPP 통합: CSPM을 CWPP·CIEM과 통합한 CNAPP으로 클라우드 보안을 일원화함

## Ⅵ. 전망
- CSPM이 CNAPP의 핵심 모듈로 통합되며, IaC 스캔·런타임 모니터링·컴플라이언스 자동화를 하나의 플랫폼에서 제공하는 방향으로 발전할 전망임
