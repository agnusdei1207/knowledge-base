## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 메인 프로세서 내에 일반 운영체제(REE)와 하드웨어적으로 완벽히 격리된 안전한 코드 실행 및 데이터 처리 영역임 |
| **배경/필요성** | 운영체제나 하이퍼바이저가 해킹되거나 관리자가 악의적일지라도 핵심 데이터와 암호키를 보호할 하드웨어 기반 방벽 필요 |
| **출제 의도** | ARM TrustZone 등 TEE의 격리 아키텍처 원리와 모바일/클라우드 환경의 데이터 보호(Data in Use) 매커니즘 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|  Rich OS (REE)    |      | Hardware Monitor  |      | Trusted OS (TEE)  |
| (일반 안드로이드) +----->| (격리 통제/스위칭)+----->| (보안 영역/암호키)|
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **REE (일반 실행 환경)** | 일반 애플리케이션과 운영체제가 실행되는 공개 영역임 | 누구나 오가는 개방형 사무실 |
| **하드웨어 모니터** | REE와 TEE 간의 메모리 접근을 하드웨어적으로 통제하고 컨텍스트 스위칭을 담당하는 게이트임 | 신원 확인 후 통과시키는 철문 |
| **TEE (신뢰 실행 환경)** | 지문 데이터, 생체 인증, DRM 암호화 등 보안이 필수적인 코드만 실행되는 격리된 영역임 | 인가자만 들어가는 1급 비밀 금고실 |

> 요약: 하나의 칩셋을 일반 구역과 보안 구역으로 물리적으로 나누어 핵심 자산의 유출을 원천 차단함.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 보안 요청   |-->| 2. 환경 스위칭 |-->| 3. TEE 내 연산 |-->| 4. 결과 반환   |
| (앱 -> 일반OS) |   | (모니터가 전환)|   | (생체인증/복호화)|   | (안전한 결괏값)|
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **보안 요청**: 일반 앱(모바일 뱅킹 등)이 결제나 지문 인식 등 보안 처리가 필요한 작업을 일반 운영체제에 요청함
2. **환경 스위칭**: 하드웨어 예외(Exception)를 발생시켜 제어권을 하드웨어 모니터(SMC)로 넘기고 TEE 모드로 전환함
3. **TEE 내 연산**: 외부(REE)에서는 메모리에 접근할 수 없는 격리 상태에서 생체 데이터 비교나 암호키 복호화를 수행함
4. **결과 반환**: 연산이 완료되면 비밀 정보 자체는 내부에 남긴 채, '성공/실패' 등의 결괏값만을 REE로 반환함

> 요약: 핵심 연산을 수행할 때만 일시적으로 닫힌 방(TEE)에 들어가 처리한 후, 결과만 밖으로 던져주는 구조임.

## Ⅳ. 문제점
* **부채널 공격(Side-channel) 취약점**: 하드웨어 격리에도 불구하고 전력 소비량, 캐시 메모리 타이밍 등을 분석하여 TEE 내부 정보를 유추해 내는 취약성 존재
* **TEE OS 자체의 취약성**: 제조사가 제공하는 TEE 내부 운영체제(TrustZone OS 등) 자체에 버그가 있을 경우 뚫리면 최고 권한을 탈취당함
* **호환성 및 표준화 파편화**: ARM TrustZone, Intel SGX 등 제조사별로 구조와 API가 제각각이어서 앱 개발 시 범용 적용이 어려움

## Ⅴ. 개선방안
* **단기 방안 (GlobalPlatform 표준 준수)**: 제조사 종속성을 탈피하기 위해 GlobalPlatform에서 제정한 TEE 범용 API 및 아키텍처 표준을 준수하여 개발
* **중기 방안 (캐시 분할 등 하드웨어 패치)**: 부채널 공격 방어를 위해 REE와 TEE 간 L1/L2 캐시 메모리를 엄격히 분할(Partitioning)하거나 플러시(Flush) 강제화
* **장기 방안 (오픈소스 펌웨어 검증)**: 블랙박스로 숨겨진 TEE 펌웨어 대신, 오픈소스로 검증된 경량 마이크로커널을 도입하여 버그를 집단지성으로 수정

## Ⅵ. 전망
* 기존에는 스마트폰(삼성 녹스, 애플 시큐어 인클레이브) 중심이었으나, 현재는 클라우드 서버 데이터 보호를 위한 핵심 기술로 확장됨
* 데이터의 전송(In Transit), 저장(At Rest)을 넘어 사용 중(In Use)인 상태까지 완벽히 보호하는 기밀 컴퓨팅의 기반 하드웨어로 진화 중임
