## Ⅰ. 개요
- **정의**: 사용자의 웹 트래픽을 중간에서 검사하여 악성 사이트 접근과 데이터 유출을 차단하는 보안 게이트웨이
- **배경/필요성**: 클라우드/SaaS 사용 증가로 기존 방화벽만으로는 웹 기반 위협을 통제할 수 없게 됨
- **비유**: 도서관 출입구에서 반입/반출 물품을 검사하는 보안 검색대와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 웹 보안 아키텍처 이해 | URL 필터링+SSL 복호화+DLP 통합 | 프록시 기반 동작 원리 서술 |

> 요약: SWG는 프록시 방식으로 웹 트래픽을 검사하여 위협 차단과 정책 준수를 동시에 수행함

## Ⅱ. 구성요소
```text
사용자 --> SWG 프록시 --> 인터넷/SaaS
              |
     +--------+--------+
     |        |        |
 URL필터  SSL검사  DLP엔진
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| URL 필터링 | 카테고리별 웹 사이트 접근을 허용/차단함 | 출입 허가 목록 |
| SSL/TLS 검사 | 암호화 트래픽을 복호화하여 내용을 검사 후 재암호화함 | 봉인 편지 개봉 검사 |
| DLP 엔진 | 민감 정보(개인정보, 기밀문서)의 외부 유출을 탐지/차단함 | 반출 금지 물품 검색 |
| 악성코드 탐지 | 다운로드 파일의 샌드박스 분석 및 시그니처 검사 수행 | 수하물 X-ray 검사 |

> 요약: URL 필터, SSL 검사, DLP, 악성코드 탐지가 프록시 위에서 계층적으로 동작함

## Ⅲ. 절차
```text
트래픽 가로채기 --> SSL 복호화 --> 정책 검사/필터링 --> 허용/차단 판정
```
- 1단계: 트래픽 가로채기 — PAC 파일 또는 에이전트를 통해 웹 요청을 SWG로 리다이렉트함
- 2단계: SSL 복호화 — HTTPS 트래픽을 중간자 인증서로 복호화하여 평문 검사를 수행함
- 3단계: 정책 검사 — URL 카테고리, 파일 해시, DLP 규칙, 악성코드 시그니처를 대조함
- 4단계: 허용/차단 판정 — 정책 위반 시 차단 페이지를 반환하고 위반 로그를 기록함

> 요약: 프록시 리다이렉트 후 복호화-검사-판정의 인라인 파이프라인으로 웹 트래픽을 통제함

## Ⅳ. 문제점
- SSL 복호화 부하: 전체 HTTPS 트래픽 복호화 시 지연 증가와 인증서 관리 복잡성 발생
- 개인정보 이슈: SSL 검사 과정에서 사용자 개인 통신 내용이 노출될 수 있음
- 우회 가능: VPN, 터널링 등으로 SWG 프록시를 우회하는 경로가 존재함

> 요약: 복호화 부하, 프라이버시 충돌, 우회 경로가 SWG 운영의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 위험 카테고리 트래픽만 선택적 SSL 복호화하여 성능과 프라이버시를 균형 조정함
2. 중기: CASB와 연동하여 SaaS 앱 수준 세밀한 정책(다운로드 차단, 공유 제한)을 적용함
3. 장기: SASE 아키텍처에 통합하여 에이전트 기반 제로 트러스트 접근과 결합함

> 요약: 선택적 복호화, CASB 연동, SASE 통합으로 SWG의 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 클라우드 기반 SWG(SECaaS)가 온프레미스 어플라이언스를 대체하는 추세
- 기술사적 판단: SSE(Security Service Edge)의 핵심 구성요소로 ZTNA, CASB와 통합 제공될 전망
- 기술사 제언: 원격근무 환경에서 에이전트 기반 SWG 배포와 SASE 전환 로드맵 수립이 필요함
