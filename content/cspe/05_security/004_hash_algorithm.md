## 미리 알고가기

- 다이제스트: 해시 함수가 출력하는 고정 길이 값임
- 역상 저항성: 해시값에서 원문을 찾기 어렵다는 성질임
- 제2역상 저항성: 특정 원문과 같은 해시값을 내는 다른 원문을 찾기 어렵다는 성질임
- 충돌 저항성: 같은 해시값을 내는 임의의 두 입력을 찾기 어렵다는 성질임
- 솔트: 비밀번호 해시 입력에 추가하는 사용자별 난수값임

## Ⅰ. 개요

- **정의/개념**: 해시 알고리즘은 임의 길이 입력을 고정 길이 다이제스트로 변환하는 일방향 함수임
- **배경/필요성**: 파일·메시지·비밀번호의 변조 여부와 동일성은 원문 전체 비교보다 짧은 검증값으로 확인할 필요가 있음

## Ⅱ. 특징

- 입력 길이와 관계없이 출력 길이가 고정됨
- 입력 1비트 변화가 다이제스트 전반에 영향을 주도록 설계함
- 해시는 암호화가 아니므로 다이제스트에서 평문을 복호화하지 않음
- 단순 해시만으로는 송신자 인증을 제공하지 않음

## Ⅲ. 종류 및 비교

| 구분 | SHA-1 | SHA-256 | SHA-3 |
|:---|:---|:---|:---|
| 계열 | SHA-1 | SHA-2 | Keccak |
| 상태 | 충돌 공격으로 신규 사용 부적합 | 범용 표준으로 사용 | SHA-2 대안 표준 |
| 구조 | Merkle-Damgard | Merkle-Damgard | Sponge 구조 |
| 적용 판단 | 레거시 검증만 제한 사용 | 파일 무결성, 서명 전 해시 | 구조 다양성·신규 설계 |

> 요약: 해시 선택은 이름보다 충돌 저항성 상태와 적용 대상의 보존 기간으로 판단함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 입력 메시지 | 해시 대상 데이터 |
| 패딩 | 블록 처리에 맞게 길이를 보정 |
| 압축 함수 | 이전 상태와 현재 블록을 결합 |
| 내부 상태 | 블록 처리 결과를 누적 |
| 다이제스트 | 검증에 사용하는 고정 길이 출력 |

```text
메시지 -> 패딩 -> 블록 분할 -> 반복 압축 -> 다이제스트
```

## Ⅴ. 원리 및 절차 흐름도

1. **입력 정규화**: 해시할 바이트열을 확정함
2. **패딩 처리**: 알고리즘 규칙에 맞게 마지막 블록을 채움
3. **블록 반복**: 각 블록을 내부 상태와 함께 압축 함수에 넣음
4. **출력 생성**: 최종 상태에서 다이제스트를 산출함
5. **검증 비교**: 수신·저장 값과 새로 계산한 값을 비교함

## Ⅵ. 실무 적용 및 유의점

- 비밀번호 저장은 단순 SHA 해시가 아니라 솔트와 KDF를 함께 사용함
- 파일 무결성 검증은 해시값 배포 경로도 신뢰해야 함
- 전자서명은 원문 전체가 아니라 해시값을 서명 입력으로 사용함
- HMAC은 비밀키를 결합해 메시지 인증까지 확인함
- MD5와 SHA-1은 충돌 저항성 문제로 신규 보안 설계에서 제외함

## Ⅶ. 결론

- 해시 알고리즘은 무결성 검증과 식별값 생성의 기반 도구임
- 답안에서는 “고유값”이라고 단정하지 말고 충돌 가능성과 계산상 탐색 난이도를 구분해야 함

## 작성 근거(검토용)

- 기존 단정 표현은 충돌 존재와 계산상 난이도 구분을 흐려서 수정함
- 해시의 역할을 암호화·인증과 분리해 HMAC, 전자서명과 연결되도록 배치함
- 표 비교는 속도보다 구조와 사용 가능 상태를 기준으로 삼음
