# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 해시 알고리즘은 임의 길이 입력을 **고정 길이 다이제스트**로 변환하는 **일방향 함수**로, SHA-256·SHA-3가 대표 표준이다.
- **왜 필요한가**: 원본을 그대로 저장·전송하지 않고도 "이 데이터가 바뀌지 않았음(무결성)"과 "원본을 되돌릴 수 없음(일방향)"을 증명해야 하는데, 해시가 이 지문(fingerprint)을 만든다.
- **핵심 직관**: 재료를 갈아 만든 스무디처럼, 같은 재료는 항상 같은 스무디가 나오지만 스무디를 보고 원래 재료를 복원할 수는 없다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래는 답안에 등장하는 모든 내부 용어를, 처음 보는 사람이 이해하도록 비유와 함께 먼저 정리한 것이다. 맨 위는 이 개념의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 일방향 함수 (상위 키워드) | 계산은 쉬우나 역산은 불가능한 함수 | 계란을 삶긴 쉬워도 되돌릴 수 없음 |
| 다이제스트(Digest) | 해시 결과로 나오는 고정 길이 요약값 | 문서 전체를 대표하는 지문 한 개 |
| 일방향성(역상저항) | 다이제스트에서 원본 입력을 못 찾음 | 스무디를 보고 원재료를 복원 불가 |
| 제2역상저항 | 특정 입력과 같은 해시를 내는 다른 입력을 못 찾음 | 내 지문과 똑같은 지문을 위조 불가 |
| 충돌저항(Collision) | 같은 해시를 내는 임의의 두 입력 쌍을 못 찾음 | 세상 누구와도 지문이 안 겹침 |
| 눈사태 효과(Avalanche) | 입력 1비트만 바뀌어도 출력 절반이 뒤집힘 | 재료 한 방울 차이로 완전히 다른 맛 |
| 압축 함수 | 블록+중간값을 받아 새 중간값을 내는 핵심 코어 | 재료를 조금씩 넣으며 반복해 가는 믹서 |
| 머클-담가드 | 블록을 순차 연결(chaining)해 해시하는 구조 | 컨베이어벨트로 블록을 한 개씩 압축 |
| 스펀지 구조(Sponge) | 흡수(absorb)·스퀴즈(squeeze)로 처리하는 SHA-3 구조 | 물을 빨아들였다 짜내는 스펀지 |
| 흡수·스퀴즈 | 메시지를 상태에 XOR 흡수 후 결과를 짜냄 | 스펀지에 물 먹이고(흡수) 짜기(스퀴즈) |
| rate·capacity | SHA-3 상태(1600b)를 나눈 처리폭·안전여유 | 스펀지의 흡수구 크기와 내부 저장고 |
| 라운드(Round) | 압축·순열을 반복 적용하는 횟수 | 반죽을 몇 번 치대는가 |
| 생일 역설·생일 공격 | n비트 해시는 약 2^(n/2)에서 충돌 발생 | 23명만 모여도 생일 겹칠 확률 50% |
| 솔트(Salt) | 비밀번호 해시에 덧붙이는 임의값 | 같은 암호도 다른 지문이 되게 하는 첨가물 |
| 길이 확장 공격 | 머클-담가드 해시에 메시지를 이어 붙이는 공격 | 중간 결과를 이어받아 뒤에 덧쓰기 |

## 깊이 이해
- **배경·문제의식**: 대칭·비대칭 암호(001·002)는 '기밀성'을 풀지만, "이 데이터가 전송 중 위·변조되지 않았는가"라는 **무결성**은 별도 도구가 필요하다. 원본과 비교하려면 원본을 갖고 있어야 하는데, 원본 대신 짧고 유일한 지문만 비교하면 되도록 만든 것이 해시다.
- **작동 원리(어떻게+왜)**:
  - 입력을 고정 크기 블록으로 자르고 패딩한 뒤, **압축 함수**를 반복 적용해 상태를 섞는다. 라운드마다 비트 회전·XOR·모듈러 덧셈으로 확산시켜 **눈사태 효과**를 만든다.
  - SHA-256은 512비트 블록을 64라운드로 압축하며, 앞 블록의 결과(중간 해시값)를 다음 블록에 넘기는 **머클-담가드** 연쇄 구조다. 그래서 마지막 블록까지 처리해야 최종 256비트 다이제스트가 나온다.
  - SHA-3(Keccak)은 구조가 다르다. 1600비트 상태에 메시지 블록을 XOR로 **흡수**하고 Keccak-f 순열(24라운드)을 돌린 뒤, 필요한 길이만큼 **스퀴즈**해 출력한다. 상태를 rate(처리폭)와 capacity(안전여유)로 나눠, capacity가 클수록 안전하다.
- **비유**: 고기 분쇄기. 어떤 고깃덩이(임의 길이 입력)를 넣어도 일정한 굵기의 다짐육(고정 길이 다이제스트)이 나오고, 다짐육을 보고 원래 부위를 복원할 수 없다(일방향).
- **구체 예시**: SHA-256 출력은 256비트(64자리 16진수)로 고정된다. `"abc"`든 1GB 영상이든 결과 길이는 같다. 충돌저항은 생일 공격 때문에 출력의 절반인 **약 128비트** 강도다(2^128 시도). SHA-1(160비트)은 2017년 SHAttered로 실제 충돌이 만들어져 폐기됐고, MD5는 이미 오래전 붕괴됐다.
- **흔한 오해·주의점**: ① 해시는 '암호화'가 아니다 — 키가 없고 복호화가 원천적으로 불가능하다(일방향). ② 해시 자체는 무결성만 보장하지 '인증'은 못 한다 — 공격자가 데이터와 해시를 함께 바꾸면 그만이므로, 키를 결합한 HMAC(005)이 필요하다. ③ 비밀번호를 SHA-256 한 번으로 저장하면 안 된다 — 빠른 해시는 무차별 대입에 취약해, 솔트+반복(bcrypt·Argon2)이 원칙이다.

## 연결 개념
- 대칭·비대칭 암호(001·002) — 기밀성을 담당, 해시는 무결성을 담당(역할 분리)
- HMAC(005) — 해시에 비밀키를 결합해 '무결성+인증'으로 확장(길이 확장 공격 방어 포함)
- 전자서명·PKI(008·009) — 원문 대신 다이제스트에 서명해 성능·부인방지 확보

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 해시는 임의 길이 입력을 고정 길이 다이제스트로 바꾸는 일방향 함수로, 역상·제2역상·충돌저항으로 무결성을 보증함.
> 2. **가치**: SHA-256(머클-담가드)·SHA-3(스펀지)이 전자서명·무결성 검증·비밀번호 저장의 기반을 이룸.
> 3. **판단 포인트**: 해시 단독은 무결성만 보장하므로 인증은 HMAC, 비밀번호는 솔트+Argon2, 신규 설계는 SHA-256 이상으로 배치해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 일방향·충돌저항의 정의와 구조 이해 확인 | 역상·제2역상·충돌저항, SHA-256 256비트·64라운드, 머클-담가드 vs 스펀지 | 무결성·인증·기밀성 혼동, 출력 비트수·라운드 오류, SHA-1 안전 표기 |

> 요약: 해시 답안은 세 저항 성질과 SHA-256·SHA-3 구조 차이를 짚고, 무결성 전용임을 명확히 해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 임의 길이 입력을 고정 길이 다이제스트로 변환하는 일방향 함수임
- 배경: 대칭·비대칭 암호(001·002)는 기밀성만 담당해, 전송·저장 데이터의 위·변조 여부를 검증할 무결성 도구가 별도로 필요함
- 필요성: SHA-256·SHA-3로 원본 대신 지문을 비교해 무결성을 검증하고, 전자서명·비밀번호 저장의 기반을 제공함

## Ⅱ. 구조 및 구성요소

선형 구조도 (두 계열):

```text
[SHA-2/머클-담가드] 입력 -> 패딩 -> 512b 블록 분할 -> 압축함수(64R) 연쇄 -> 256b 다이제스트
[SHA-3/스펀지]      입력 -> 패딩 -> rate 흡수(XOR) -> Keccak-f 순열(24R) -> 스퀴즈 -> 다이제스트
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 압축 함수/순열 | 블록을 반복 섞어 확산 | SHA-256 64R, Keccak-f 24R |
| 체이닝/상태 | 블록 간 중간값 전달 | 머클-담가드는 연쇄, 스펀지는 1600b 상태 |
| 패딩 | 입력을 블록 크기에 정렬 | 원본 길이 정보 포함 |
| 다이제스트 | 고정 길이 출력 | SHA-256=256b, SHA3-256=256b |

> 요약: 해시는 압축·순열의 반복으로 눈사태 효과를 내며, SHA-2는 연쇄, SHA-3는 흡수·스퀴즈로 상태를 처리함.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도:

```text
원본 입력 -> 패딩·블록 분할 -> 압축함수/순열 반복 적용 -> 최종 다이제스트 산출 -> 수신측 재계산·비교
```

1. 송신측이 입력을 패딩 후 고정 크기 블록으로 분할함
2. 각 블록에 압축 함수(SHA-256 64라운드) 또는 Keccak-f 순열(24라운드)을 반복 적용해 상태를 확산시킴
3. 마지막 블록까지 처리해 고정 길이 다이제스트를 산출하고, 데이터와 함께 전달함
4. 수신측이 받은 데이터로 해시를 재계산해 전달받은 다이제스트와 일치하는지 비교해 무결성을 판정함

## Ⅳ. 특징

- 일방향성 — 다이제스트에서 원본을 복원할 수 없어 비밀번호·토큰 저장에 활용됨
- 충돌저항 — n비트 출력은 생일 공격으로 약 2^(n/2) 강도(SHA-256은 약 128비트)를 가짐
- 눈사태 효과 — 입력 1비트 변화가 출력 약 절반을 뒤집어 미세 변조를 즉시 탐지함
- 고정 길이·결정성 — 입력 크기와 무관하게 동일 길이 출력이며 같은 입력은 항상 같은 값
- 무결성 전용 한계 — 키가 없어 인증·부인방지는 불가하므로 HMAC·전자서명과 결합이 필요함

## Ⅴ. 심화 비교 및 적용 판단

- SHA-2와 SHA-3는 안전 강도는 유사하나 내부 구조가 달라, 특정 공격 내성과 성능 관점에서 선택이 갈림.

| 구분 | SHA-2(SHA-256) | SHA-3(SHA3-256) |
|:---|:---|:---|
| 내부 구조 | 머클-담가드 연쇄 | Keccak 스펀지(흡수·스퀴즈) |
| 라운드 | 블록당 64라운드 | 순열당 24라운드 |
| 길이 확장 공격 | 취약(HMAC로 보완) | 구조적으로 안전 |
| 위상 | 현재 최다 사용 표준 | 구조 다양성 확보용 대안 |

> 요약: 범용은 검증·성능이 앞선 SHA-256, 길이 확장 내성·알고리즘 다양성이 필요하면 SHA-3를 선택함.

- 리스크 — 취약 해시 잔존: MD5·SHA-1 사용이 원인 → SHA-256 이상 강제·CI 스캔으로 대응
- 리스크 — 비밀번호 저평가 해시: 빠른 해시 단독 저장이 원인 → 솔트+Argon2·bcrypt 적용으로 대응
- 리스크 — 무결성·인증 혼동: 해시만으로 인증 가정이 원인 → HMAC·전자서명 결합으로 대응

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 무결성 검증: 배포 파일·컨테이너 이미지에 SHA-256 체크섬을 게시하고 다운로드 측 재계산 비교를 강제함
2. 비밀번호 저장: SHA-256 단독 대신 솔트+Argon2id(메모리·반복 파라미터)로 무차별 대입 비용을 상향함
3. 전자서명 결합: 원문 대신 SHA-256 다이제스트에 서명해 성능을 확보하고 SHA-1 서명은 차단함

**결론:**
- 조건부 판단: 신규 설계는 SHA-256을 기본으로 하되, 무결성·인증·기밀성 요구를 구분해 HMAC·서명·암호화를 각각 배치해야 함
- 향후 방향: 양자 시대에도 해시는 출력 길이를 늘리면(SHA-384·SHA3-512) 유지 가능하나, 그로버 공격 대비 여유 강도를 확보해야 함
