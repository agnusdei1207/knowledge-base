## 미리 알고가기

- 보안 정책은 조직이 반드시 지켜야 할 상위 원칙과 요구사항임
- 지침은 정책을 특정 영역에 적용하기 위한 권고와 해석 기준임
- 절차는 담당자가 실제로 수행할 단계와 입력·출력물을 정한 실행 문서임

## Ⅰ. 개요

- **정의/개념**: 보안 정책·지침·절차는 조직 보안 요구를 상위 원칙, 적용 기준, 실행 단계로 나누어 일관된 보안 운영을 가능하게 하는 문서 체계임
- **배경/필요성**: 정책만 있으면 현장 실행이 모호하고 절차만 있으면 방향성이 약해짐. 원칙과 기준과 실행을 계층화해야 조직 전체가 같은 방식으로 움직임

## Ⅱ. 특징

- 문서 계층이 명확해야 예외 승인과 감사 기준이 흔들리지 않음
- 정책은 안정적으로 유지하고 지침과 절차는 기술 변화에 맞춰 자주 갱신함
- 담당자, 승인자, 증적을 포함해야 실제 운영과 감사에 연결됨
- 클라우드와 DevSecOps 환경에서는 일부 정책을 코드와 자동 검사로 구현할 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 정책 | 지침 | 절차 |
|:---|:---|:---|:---|
| 역할 | 무엇을 지켜야 하는지 선언함 | 어떻게 해석하고 적용할지 제시함 | 어떤 순서로 수행할지 정함 |
| 수준 | 전사 상위 원칙 | 영역별 기준 | 업무별 실행 단계 |
| 변경 주기 | 낮음 | 중간 | 높음 |
| 예시 | 접근통제 정책 | 비밀번호 설정 지침 | 계정 발급·회수 절차 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정책 체계 | 정보보호, 개인정보보호, 접근통제, 암호화 같은 상위 요구를 정리한 문서층임 |
| 지침 체계 | 정책을 시스템, 클라우드, 개발, 운영 환경에 맞게 풀어 주는 기준층임 |
| 절차 체계 | 계정 신청, 권한 승인, 로그 점검, 사고 보고처럼 반복 업무를 수행하는 실행층임 |
| 예외 승인 | 정책을 지키기 어려운 상황에서 위험과 기한과 보완 조치를 승인하는 통제임 |
| 문서 생명주기 | 제정, 승인, 배포, 교육, 점검, 폐기를 관리해 문서 최신성을 유지하는 절차임 |

```text
정책 -> 표준/지침 -> 절차 -> 작업 지시서/체크리스트 -> 증적
```

## Ⅴ. 원리 및 절차 흐름도

```text
요구 식별 -> 정책 수립 -> 지침 구체화 -> 절차 작성 -> 교육/배포 -> 점검/개정
```

1. **요구 식별**: 법규, 표준, 위험평가, 감사 지적을 문서 요구로 정리함
2. **정책 수립**: 전사적으로 지켜야 할 상위 원칙과 책임을 승인함
3. **지침 구체화**: 영역별 적용 기준과 최소 요구 수준을 정함
4. **절차 작성**: 담당자, 입력, 처리 단계, 출력 증적을 명시함
5. **점검과 개정**: 교육, 감사, 사고 경험을 반영해 문서를 갱신함

## Ⅵ. 실무 적용 및 유의점

1. 계정과 권한 관리는 정책, 지침, 절차가 서로 다른 표현을 쓰면 감사에서 흔들리므로 문서 간 불일치 건수와 예외 승인 만료 건수로 정합성을 관리함
2. 클라우드 인프라는 절차 문서만 배포하지 말고 정책 코드를 자동 검사에 연결하며 차단된 위반 배포 수와 수동 예외 처리 시간을 확인함

## Ⅶ. 결론

- 보안 정책·지침·절차는 문서를 늘리는 일이 아니라 보안 의사결정과 현장 실행과 감사 증적을 같은 기준으로 묶는 체계임
