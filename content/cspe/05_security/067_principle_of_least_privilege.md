# 📖 【암기용】 개념 완전 이해

> 목적: 최소 권한 원칙을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사용자, 서비스, 프로세스가 업무 수행에 필요한 최소 권한만 갖도록 제한하는 접근통제 원칙
- **왜 필요한가**: 계정 탈취와 내부 오남용은 권한 범위만큼 피해가 커진다. 권한을 줄이면 동일 침해에서도 데이터 접근, 명령 실행, lateral movement 범위가 제한된다.
- **핵심 직관**: 건물 출입카드를 전 층 마스터키가 아니라 본인 업무 구역과 시간대에만 열리게 만드는 방식이다.

## 깊이 이해
- **배경·문제의식**: 운영 편의로 관리자 권한, 공유 계정, 영구 토큰을 부여하면 공격자는 인증 우회 없이 정상 권한으로 움직인다. 최소 권한은 과다 권한을 제거해 신뢰 경계를 세분화한다.
- **작동 원리**: 역할 기반 RBAC, 속성 기반 ABAC, 정책 기반 PBAC로 권한을 정의하고 JIT, PAM, MFA, SoD로 특권 사용을 통제한다. 권한은 부여, 사용, 만료, 회수, 감사 로그로 관리한다.
- **비유**: 병원에서 의사는 담당 환자 차트만 보고, 약사는 처방 항목만 수정하며, 응급 상황은 승인 기록을 남기는 것과 같다.
- **구체 예시**: 개발자에게 운영 DB `SELECT` 권한을 상시 부여하지 않고, PAM 승인 후 30분 JIT 세션으로 접속하며 SQL 감사 로그를 SIEM에 전송한다.
- **흔한 오해·주의점**: 최소 권한은 권한을 무조건 줄이는 활동이 아니다. 업무 수행 권한은 보장하되 과다 권한, 영구 권한, 공유 권한, 미사용 권한을 제거하는 균형 원칙이다.

## 연결 개념
- RBAC/ABAC/PBAC - 권한 모델링 방식
- PAM/JIT - 특권 계정 사용 시간과 세션 제어
- Zero Trust - 모든 요청을 신원, 단말, 위치, 위험도 기준으로 재검증

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 최소 권한 답안은 RBAC/ABAC/JIT/PAM/SoD를 나열하지 말고 권한 생명주기와 신뢰 경계 축소, 로그 재검증으로 연결해야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 최소 권한 원칙은 사용자·프로세스·서비스에 업무 수행에 필요한 권한만 시간·범위·행위 단위로 부여하는 통제임.
> 2. **가치**: 탈취 계정의 접근 범위, 데이터 조회 범위, 명령 실행 범위를 제한해 침해 확산을 줄임.
> 3. **판단 포인트**: 정적 RBAC만으로는 부족하며 ABAC, JIT, PAM, SoD, 권한 리뷰, 감사 로그를 결합해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 접근통제 원칙 이해 확인 | need-to-know, need-to-use, AC-6, 권한 최소화 | 권한 축소를 업무 차단으로 설명 |
| 구현 방식 판단 확인 | RBAC, ABAC, JIT, PAM, MFA, SoD | RBAC만 쓰고 특권 계정 통제 누락 |
| 운영·감사 역량 확인 | 권한 요청, 승인, 만료, 회수, 로그 분석 | 퇴사자·전보자 권한 회수 누락 |

> 요약: 이 문제는 최소 권한 원칙을 신뢰 경계 축소와 권한 생명주기 운영 통제로 설명해야 함.

---

## Ⅰ. 개요 및 필요성

최소 권한은 권한 범위 축소 원칙임. 사용자와 서비스는 필요한 자원, 행위, 시간에 대해서만 권한을 가져야 한다. 클라우드 IAM, 운영 DB, API 토큰, 관리자 계정에서 과다 권한은 계정 탈취 시 피해 범위와 감사 리스크를 키우므로 지속적인 권한 재검토가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
신원/업무 -> 역할/속성 정책 -> 권한 승인 -> JIT/PAM 세션
          -> 접근 실행 -> 로그/감사 -> 권한 리뷰/회수
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| RBAC | 직무 역할 기준 권한 묶음 부여 | 운영자, 개발자, 감사자 분리 |
| ABAC/PBAC | 속성·정책 기반 세밀한 판단 | 위치, 단말 상태, 시간, 데이터 등급 |
| JIT/PAM | 특권 권한을 승인 시간 동안만 부여 | 세션 녹화, MFA, 명령 통제 |
| SoD | 승인자와 수행자 역할 분리 | 결재, 배포, 감사 권한 분리 |
| Access Review | 미사용·전보·퇴사 권한 회수 | 분기별 리뷰, owner 승인 |

> 요약: 최소 권한은 권한 모델, 특권 세션, 직무 분리, 정기 리뷰가 함께 작동해야 운영 통제가 됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
접근 요청 -> 신원/업무/위험도 확인 -> 정책 평가
-> 승인 또는 거절 -> JIT 권한 부여 -> 행위 로그 수집
-> 만료/회수 -> 권한 리뷰와 재검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자, 서비스, 데이터 등급 식별 | owner와 업무 목적 기록 |
| 2 | RBAC/ABAC 정책으로 허용 행위 산정 | wildcard 권한 0건 |
| 3 | 고위험 권한은 PAM 승인과 MFA 적용 | privileged session 100% 기록 |
| 4 | 접근 로그, 명령 로그, API 호출 수집 | SIEM 전송 누락 0건 |
| 5 | 미사용 권한과 만료 권한 회수 | 90일 미사용 권한 0건 |

> 요약: 최소 권한은 요청 시 정책 평가, 사용 중 로그 수집, 사용 후 만료·회수로 권한을 계속 재검증함.

## Ⅳ. 특징

| 구분 | 광범위 권한 | 최소 권한 원칙 | 수치/판단 포인트 |
|:---|:---|:---|:---|
| 권한 범위 | 관리자·와일드카드 권한 | 자원·행위·시간 제한 | `*:*` 정책 0건 |
| 운영 방식 | 상시 권한 | JIT 승인 후 만료 | 특권 세션 30~120분 |
| 책임 추적 | 공유 계정 | 개인 계정, 세션 로그 | 공유 계정 0건 |
| 감사 대응 | 사후 확인 | 승인, 사용, 회수 증적 | 분기별 access review |

> 요약: 최소 권한은 권한 범위와 사용 시간을 줄이고 개인별 로그를 남겨 침해 확산과 감사 공백을 통제함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 정적 RBAC | RBAC + ABAC + JIT + PAM | 클라우드·DevOps처럼 변경이 많은 환경 |
| 비용/운영 | 권한 요청 적음 | 승인·만료·로그 운영 필요 | privileged account 20개 이상 |
| 위험 통제 | 업무 편의 우선 | 탈취 계정 피해 범위 제한 | 개인정보·결제·운영 DB 접근 시 |

> 요약: 단순 RBAC는 직무 기준 권한에 적합하고, 고위험 운영 환경은 JIT/PAM과 속성 기반 재검증이 필요함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과다 권한 | 초기 편의 권한 유지 | access review, least privilege policy | 과다 권한 제거율 95% |
| 권한 누적 | 전보·프로젝트 종료 후 미회수 | HR 연동, 자동 deprovisioning | 퇴사자 권한 0건 |
| 특권 오남용 | 공유 관리자 계정 | PAM, MFA, 세션 녹화 | 공유 계정 0건 |
| 업무 지연 | 승인 절차 과다 | risk-based JIT, break-glass | 승인 SLA 30분 |

> 요약: 과다 권한과 권한 누적은 자동 회수로, 특권 오남용은 PAM과 개인별 로그로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 권한 정확도 | 업무 역할-권한 매칭률 95% | IAM policy review |
| 특권 통제 | PAM 적용률 100%, MFA 100% | PAM report, IdP 로그 |
| 회수 관리 | 퇴사자 24시간, 전보자 7일 내 회수 | HR-IAM 연동 로그 |
| 감사 추적 | 관리자 명령·API 호출 1년 보관 | SIEM, session recording |

> 요약: 최소 권한 운영은 권한 정확도, PAM 적용률, 회수 시간, 감사 로그 보관으로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 권한 모델링: RBAC로 기본 역할을 만들고 ABAC로 데이터 등급, 접속 위치, 단말 보안 상태, 시간 조건을 추가함.
2. 특권 통제: 운영 DB, root, cloud admin은 PAM, MFA, JIT 30~120분 세션, 명령 로그, 승인 ticket을 필수화함.
3. 재검증 운영: HR 시스템과 IAM을 연동해 퇴사 24시간, 전보 7일 내 권한 회수와 분기별 access review를 수행함.

**결론 (2줄):**
- 기술사 판단: 일반 업무 권한은 RBAC, 고위험 데이터·운영 권한은 ABAC와 JIT/PAM을 결합해야 함.
- 향후 방향: Zero Trust, CIEM, identity threat detection과 연계해 권한 부여보다 권한 사용 행위의 지속 검증으로 확장됨.

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|

| 요구사항 명시형 | "IAM 개선 방안을 제시하시오", "특권 계정 통제를 설계하시오" | RBAC/ABAC/JIT/PAM/SoD 적용 절차 | 승인 SLA, access review, 감사 로그 |
