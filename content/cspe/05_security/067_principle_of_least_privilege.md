## 미리 알고가기

- 최소 권한 원칙은 사용자와 서비스와 프로세스에 필요한 범위의 권한만 부여하는 접근통제 원칙임
- 계정 탈취 피해는 취약점의 심각도보다 그 계정이 가진 권한 범위에 더 크게 좌우됨
- 최소 권한은 무조건 권한을 줄이는 것이 아니라 업무 수행에 필요한 권한을 시간과 범위와 행위 기준으로 정확히 부여하는 것임

## Ⅰ. 개요

- **정의/개념**: 최소 권한 원칙은 주체가 업무 수행에 필요한 최소 범위의 데이터, 기능, 시스템에만 접근하도록 권한을 제한하는 보안 원칙임
- **배경/필요성**: 편의상 넓게 부여된 관리자 권한과 공유 계정과 영구 토큰은 계정 탈취나 내부 오남용 시 피해를 급격히 키우므로 권한 범위를 세분화할 필요가 있음

## Ⅱ. 특징

- 권한을 사용자뿐 아니라 애플리케이션 계정, API 토큰, 배치 프로세스에도 적용해야 함
- 역할 기반 부여와 함께 시간 제한과 승인 절차와 주기적 회수가 중요함
- 최소 권한은 권한 설계와 운영 검토가 함께 있어야 유지됨
- 미사용 권한과 예외 권한을 방치하면 정책은 있어도 실제 위험은 줄지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 과다 권한 운영 | 최소 권한 운영 |
|:---|:---|:---|
| 권한 범위 | 관리자·광범위 접근 상시 부여 | 역할과 업무 기준으로 제한 부여 |
| 사고 영향 | 탈취 시 피해 범위가 큼 | 접근 범위와 이동 범위를 줄임 |
| 운영 편의 | 초기 설정은 쉬움 | 설계와 승인과 주기 리뷰가 필요함 |
| 감사 대응 | 권한 근거가 불명확함 | 부여 사유와 회수 이력이 남음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 권한 모델 | 역할, 속성, 자원별 권한 기준을 정의함 |
| 부여와 승인 | 요청, 승인, 기간, 사유를 기록하며 권한을 부여함 |
| 사용 통제 | MFA, 세션 기록, 특권 접근 통제로 사용 범위를 제한함 |
| 정기 검토와 회수 | 미사용 권한과 퇴직·전보 권한을 회수함 |

```text
권한 기준 정의 -> 요청/승인 -> 제한된 사용 -> 주기 리뷰 -> 회수/수정
```

## Ⅴ. 원리 및 절차 흐름도

```text
업무 식별 -> 필요 권한 매핑 -> 최소 범위 부여 -> 사용 기록 수집 -> 리뷰/회수
```

1. **업무 식별**: 어떤 자원과 행위가 필요한지 정의함
2. **권한 매핑**: 역할과 자원과 행위를 연결해 최소 범위를 설계함
3. **제한 부여**: 기간과 조건을 붙여 권한을 부여함
4. **사용 기록 수집**: 실제 사용 이력과 특권 사용 로그를 남김
5. **리뷰와 회수**: 불필요하거나 미사용인 권한을 정리함

## Ⅵ. 실무 적용 및 유의점

1. 운영 DB와 클라우드 관리 콘솔처럼 피해 파급이 큰 자산은 상시 관리자 권한을 없애고 승인 기반 임시 권한으로 전환해야 하며 영구 특권 계정 수 감소와 특권 세션 기록 완전성과 미사용 권한 회수율로 확인함
2. 애플리케이션 간 API 연동은 서비스 계정 권한이 과다해지기 쉬우므로 읽기·쓰기 범위와 리소스 범위를 분리하고 주기적으로 토큰을 교체해야 하며 권한 오남용 탐지 건수와 서비스 계정 권한 축소 여부로 확인함

## Ⅶ. 결론

- 최소 권한 원칙은 계정 탈취와 내부 오남용의 피해 범위를 줄이는 가장 기본적인 접근통제이므로 부여 기준과 사용 통제와 회수 절차가 함께 운영돼야 함
