## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 공인된 인증 기관을 통해 전자 인증서를 발급하고 공개키를 신뢰성 있게 관리하는 종합 체계임 |
| **배경/필요성** | 비대칭 암호 환경에서 배포되는 공개키의 소유자 신원을 제3자가 신뢰성 있게 증명할 구조 필요 |
| **출제 의도** | 공개키 위장 공격(MITM)을 방어하기 위한 신뢰 모델과 PKI의 핵심 구성 요소 간 역할 이해도 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|       User        |      | Registration Auth |      | Certificate Auth  |
| (키 쌍 생성/사용) +----->| (RA, 신원 확인)   +----->| (CA, 인증서 발급) |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **인증 기관 (CA)** | 인증서의 발급, 갱신, 폐기를 총괄하는 신뢰할 수 있는 제3의 최상위 기관임 | 국가 여권 발급청 |
| **등록 기관 (RA)** | 사용자의 신원을 물리적/논리적으로 검증하고 CA에 인증서 발급을 요청하는 대행 기관임 | 구청 여권 민원실 |
| **저장소 (Repository)** | 발급된 인증서와 폐지 목록(CRL)을 저장하여 누구나 조회할 수 있게 하는 디렉터리임 | 온라인 여권 진위조회 시스템 |

> 요약: 신뢰할 수 있는 제3자(CA/RA)가 주도하여 디지털 환경의 신분증명(인증서)을 총괄하는 체계임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 키 생성/신청|-->| 2. 신원 검증   |-->| 3. 인증서 발급 |-->| 4. 인증서 검증 |
| (사용자 수행)  |   | (RA가 확인)    |   | (CA가 서명)    |   | (상대방 확인)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **키 생성 및 신청**: 사용자가 개인키와 공개키 쌍을 생성한 후 공개키를 첨부하여 RA에 인증서를 신청함
2. **신원 검증**: RA가 신청자의 신분증명서류 등을 대면/비대면으로 확인하여 정당한 사용자인지 심사함
3. **인증서 발급**: CA가 검증된 공개키에 자신의 개인키로 전자서명을 생성하여 X.509 인증서를 발급함
4. **인증서 검증**: 통신 상대방은 CA의 공개키를 이용해 사용자 인증서의 유효성을 조회 및 검증함

> 요약: 사용자 신청 후 신원 검증을 거쳐 CA가 보증 서명한 인증서를 발급 및 유통하는 생명주기 절차임.

## Ⅳ. 문제점
* **단일 장애점(SPOF)**: 최상위 Root CA가 해킹당하거나 개인키가 유출될 경우 하위 모든 인증 체계가 완전히 붕괴됨
* **관리 및 갱신의 복잡성**: 수백만 개의 인증서 라이프사이클(발급, 갱신, 폐기)을 실시간으로 관리하는 데 막대한 비용 소요
* **폐기 정보의 지연**: 인증서 폐지 목록(CRL)의 갱신 주기 차이로 인해 폐기된 인증서가 유효한 것으로 오인될 위험

## Ⅴ. 개선방안
* **단기 방안 (OCSP 도입)**: 주기적 갱신인 CRL 대신 실시간으로 인증서 상태를 확인하는 온라인 상태 검증(OCSP) 도입
* **중기 방안 (분산 관리 및 다중 서명)**: CA의 개인키를 HSM에 보관하고 여러 관리자의 다중 서명으로 단일 장애점(SPOF) 위협 완화
* **장기 방안 (블록체인 분산 PKI)**: 중앙 집중형 CA를 대체하는 분산 원장 기반의 DID(분산 신원 증명) 등 탈중앙화 신원 체계로 전환

## Ⅵ. 전망
* 제로 트러스트(Zero Trust) 아키텍처 환경에서 기기 및 사용자 상호 인증을 위한 핵심 기반 인프라로 그 중요성이 더욱 확대됨
* 클라우드 네이티브 환경에 맞춰 단기 유효기간 인증서의 자동화된 발급/갱신(ACME 프로토콜 등)이 주류로 자리잡고 있음
