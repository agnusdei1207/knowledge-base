## 미리 알고가기

- 샌드박스는 프로그램을 제한된 공간 안에서만 실행하게 하는 격리 환경임
- 마이크로 VM은 빠르게 띄우고 버릴 수 있는 경량 가상머신임
- 폭발 반경은 사고가 났을 때 피해가 퍼지는 범위를 말함

## Ⅰ. 개요

- **정의/개념**: 에이전트 샌드박스 격리는 코드 실행이나 파일 조작 도구를 가진 에이전트의 행동이 호스트와 내부망으로 번지지 않게 실행 환경을 가두는 구조임
- **배경/필요성**: 프롬프트 필터와 권한 통제가 있어도 우회나 환각을 완전히 없앨 수 없음. 실제 실행 단계에서는 침해 가정 격리가 필요함

## Ⅱ. 특징

- 공격을 막지 못해도 피해 범위를 좁히는 마지막 방어선 역할을 함
- 파일 시스템, 네트워크, 프로세스, 비밀 값 접근을 각각 잘라 낼 수 있음
- 일회용 실행 환경과 짧은 수명을 유지할수록 잔존 위험이 줄어듦
- 권한 통제와 함께 써야 효과가 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | 가드레일·권한 통제 | 샌드박스 격리 |
|:---|:---|:---|
| 막는 시점 | 실행 전에 위험 행동을 제한함 | 실행 중 또는 실행 뒤 피해 확산을 막음 |
| 주된 수단 | 정책, 승인, 최소 권한 | 격리 런타임, 네트워크 차단, 임시 파일 공간 |
| 실패했을 때 | 위험 행동이 그대로 실행될 수 있음 | 실행돼도 호스트 침해 범위를 줄일 수 있음 |
| 함께 써야 하는 이유 | 사전 통제에 강함 | 침해 가정 대응에 강함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 에이전트 런타임 | 작업 계획과 도구 선택을 담당하지만 직접 호스트 권한을 가져서는 안 됨 |
| 격리 실행기 | 마이크로 VM이나 제한된 컨테이너에서 실제 코드를 실행함 |
| 파일 경계 | 필요한 파일만 읽게 하고 결과물만 밖으로 꺼냄 |
| 네트워크 정책 | 외부 접속과 내부망 접근 범위를 세밀하게 제한함 |
| 종료·정리 절차 | 작업이 끝나면 인스턴스와 임시 데이터를 바로 없앰 |

```text
에이전트 요청 -> 격리 실행기 생성 -> 제한된 코드 실행 -> 결과만 반출 -> 인스턴스 폐기
```

## Ⅴ. 원리 및 절차 흐름도

```text
작업 요청 수신 -> 격리 환경 생성 -> 제한된 권한으로 실행 -> 로그와 결과 수집 -> 환경 삭제
```

1. **작업 요청 수신**: 에이전트가 코드 실행이나 파일 처리를 요청함
2. **격리 환경 생성**: 임시 샌드박스를 새로 띄움
3. **제한된 권한 실행**: 파일, 네트워크, 시스템 호출을 제한한 채 작업함
4. **결과 수집**: 필요한 산출물과 로그만 밖으로 가져옴
5. **환경 삭제**: 샌드박스를 바로 없애 잔여 흔적을 줄임

## Ⅵ. 실무 적용 및 유의점

1. 코드 실행 에이전트는 일회용 샌드박스와 외부망 제한을 기본값으로 두고 차단된 시스템 호출 수와 비허용 외부 접속 시도로 점검함
2. 내부 데이터 에이전트는 애플리케이션 서버와 실행 환경을 분리하고 탈출 시험과 잔존 파일 검사로 샌드박스 탈출 재현율을 확인함

## Ⅶ. 결론

- 샌드박스 격리는 에이전트가 틀릴 수 있다는 전제 위에 서는 방어이므로 실행 환경 분리가 보안 설계의 기본선이 됨
