## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 조직 내 사용자·서비스의 신원(Identity) 생명주기를 관리하고, 리소스에 대한 접근 권한을 중앙에서 제어·감사하는 체계임 |
| **배경/필요성** | 클라우드·하이브리드 환경에서 사용자·서비스 계정이 급증하며, 프로비저닝·접근 제어·감사의 일원화가 필수임 |
| **출제 의도** | IAM의 구성요소(프로비저닝·인증·인가·감사)와 클라우드 IAM의 특성을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 프로비저닝| --> |  인증    | --> |  인가    |
| (생명주기)|     | (AuthN)  |     | (AuthZ)  |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 프로비저닝 | 계정 생성·변경·비활성화·삭제의 생명주기를 자동 관리함 | 입사·전보·퇴사 인사 절차 |
| 인증 | MFA·SSO·FIDO2 등으로 사용자 신원을 검증함 | 출입증 확인 |
| 인가 | RBAC·ABAC 정책에 따라 리소스 접근 권한을 결정함 | 층별 출입 권한 |

> 요약: 프로비저닝(생명주기) → 인증(신원 확인) → 인가(권한 결정) → 감사(이력 기록)로 신원과 접근을 통합 관리함.

## Ⅲ. 절차
```
+------------+     +------------+
| 계정생성   | --> | 역할/권한  |
| (입사)     |     | 할당       |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 계정삭제   | <-- | 접근감사   |
| (퇴사)     |     | 정기리뷰   |
+------------+     +------------+
```

1. 계정 생성: HR 시스템 연동으로 입사 시 자동 계정 프로비저닝을 수행함
2. 역할·권한 할당: 직무에 따른 역할을 할당하고, 최소 권한 원칙을 적용함
3. 접근 감사: 정기적 접근 리뷰(Access Certification)로 과도한 권한을 식별·회수함
4. 계정 비활성화·삭제: 퇴사·이동 시 계정을 즉시 비활성화하고 일정 기간 후 삭제함

> 요약: 생성 → 할당 → 감사 → 삭제로 계정 생명주기를 자동화하고 권한을 통제함.

## Ⅳ. 문제점
- 권한 누적: 부서 이동 시 이전 권한이 회수되지 않아 과도한 권한이 축적(Privilege Creep)됨
- 고아 계정: 퇴사자·비활성 계정이 방치되어 내부자 위협·공격 경로로 악용됨
- 멀티 클라우드 분산: AWS·Azure·GCP 각각의 IAM 정책이 상이하여 통합 관리가 어려움

## Ⅴ. 개선방안
- (단기) 자동 디프로비저닝: HR 시스템과 IAM을 SCIM으로 연동하여 퇴사 즉시 계정을 비활성화함
- (중기) 정기 접근 리뷰: 분기별 Access Certification으로 불필요한 권한을 식별·회수함
- (장기) CIEM 도입: 멀티 클라우드 환경의 ID·권한을 통합 가시화·최적화하는 CIEM을 적용함

## Ⅵ. 전망
- IGA(Identity Governance & Administration)와 CIEM의 통합으로 온프레미스·멀티 클라우드 전체의 신원·권한을 단일 플랫폼에서 관리하는 방향으로 발전할 전망임
