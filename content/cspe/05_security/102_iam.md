## 미리 알고가기

- IAM은 사람과 서비스 계정을 만들고 변경하고 삭제하는 신원 생명주기와 접근 권한을 함께 관리하는 체계임
- 인증은 누구인지 확인하는 것이고, 인가는 무엇을 할 수 있는지 정하는 것임
- IAM은 로그인 기능만이 아니라 입사·이동·퇴사와 권한 리뷰까지 포함하는 운영 체계로 봐야 함

## Ⅰ. 개요

- **정의/개념**: IAM은 사용자와 서비스의 계정 생성과 변경과 폐기, 인증 방식, 권한 부여, 감사 이력을 중앙에서 관리해 신원과 접근을 통합 통제하는 체계임
- **배경/필요성**: 클라우드와 SaaS와 내부 시스템이 늘면서 계정과 권한이 분산되기 쉬워졌고, 수작업으로는 과다 권한과 고아 계정을 줄이기 어려워 중앙 관리가 필요함

## Ⅱ. 특징

- 계정 생명주기와 인증과 권한 관리와 감사를 한 체계로 묶음
- 인사 정보와 연계하면 입사·이동·퇴사 처리 자동화가 가능함
- 사용자 계정뿐 아니라 API 키와 서비스 계정도 포함해야 실효성이 생김
- 권한 설계와 리뷰가 약하면 도입만으로는 과다 권한이 줄지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 개별 시스템 계정 관리 | 중앙 IAM |
|:---|:---|:---|
| 계정 생성/회수 | 시스템별 수작업 | 중앙 정책과 자동화 가능 |
| 인증 정책 | 서비스마다 다름 | MFA와 SSO를 일관 적용하기 쉬움 |
| 권한 감사 | 분산돼 추적이 어려움 | 통합 리뷰와 보고가 가능함 |
| 주요 한계 | 고아 계정과 권한 누적 | 연계 시스템 품질과 역할 모델 설계가 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Identity Lifecycle | 계정 생성, 변경, 비활성화, 삭제를 관리함 |
| Authentication | 비밀번호, MFA, SSO, 패스키 같은 인증 방식을 관리함 |
| Authorization | 역할과 속성과 정책에 따라 권한을 부여함 |
| Governance and Audit | 접근 리뷰와 위반 탐지와 증적 관리를 수행함 |

```text
계정 생성 -> 인증 정책 적용 -> 권한 부여 -> 사용/감사 -> 이동·회수·삭제
```

## Ⅴ. 원리 및 절차 흐름도

```text
입사/요청 -> 계정 프로비저닝 -> 역할 할당 -> 로그인/사용 -> 정기 리뷰 -> 퇴사/비활성화
```

1. **계정 프로비저닝**: 사용자나 서비스 계정을 생성함
2. **역할과 권한 할당**: 업무 기준으로 최소 권한을 부여함
3. **인증 정책 적용**: MFA와 SSO 같은 정책을 강제함
4. **정기 리뷰**: 미사용 계정과 과다 권한을 확인함
5. **비활성화와 삭제**: 퇴사나 종료 시 권한을 회수함

## Ⅵ. 실무 적용 및 유의점

1. 인사 이동이 잦은 조직은 IAM과 인사 시스템 연계로 계정 생성과 회수를 자동화하고 권한 리뷰와 미사용 계정 탐지를 함께 운영한 뒤 퇴사 계정 비활성화 지연과 권한 누적 감소 여부로 확인함
2. 멀티 클라우드 환경은 사용자 계정만 보면 사각지대가 남으므로 서비스 계정과 API 키까지 범위에 넣고 고아 자격 증명 감소와 공통 인증 정책 적용률로 확인함

## Ⅶ. 결론

- IAM은 로그인 시스템이 아니라 계정 생명주기와 권한 통제를 중앙에서 관리해 과다 권한과 고아 계정을 줄이는 운영 기반임
