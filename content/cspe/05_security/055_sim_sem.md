## 미리 알고가기

- SIM은 장기 로그 보관과 검색과 보고에, SEM은 실시간 이벤트 상관분석과 경보에 초점이 있었음
- 현대 SIEM은 두 기능을 통합한 형태로 발전했으므로 SIM과 SEM은 역사적 구성 요소로 이해하는 것이 좋음
- 저장 중심 기능과 실시간 탐지 기능의 차이를 알아야 SIEM 설계 목적이 분명해짐

## Ⅰ. 개요

- **정의/개념**: SIM은 보안 로그 장기 저장·검색·보고 기능이고, SEM은 실시간 이벤트 상관분석·경보 기능임
- **배경/필요성**: 감사 로그 보관과 실시간 침해 탐지는 요구가 다름. 이후 두 기능이 현대 SIEM으로 통합됨

## Ⅱ. 특징

- SIM은 장기 보관, 사후 조사, 보고서 생성에 강점이 있음
- SEM은 실시간 규칙과 상관분석으로 즉시 대응 가능한 경보를 만듦
- 두 기능이 결합돼야 감사 대응과 침해 대응을 한 플랫폼에서 운영함
- 저장과 탐지를 같은 비용 구조로 보면 과수집과 성능 병목이 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | SIM | SEM | SIEM |
|:---|:---|:---|:---|
| 초점 | 장기 저장과 검색 | 실시간 상관분석 | 저장 + 상관분석 통합 |
| 주요 산출물 | 보고서와 포렌식 근거 | 경보와 사건 후보 | 경보, 검색, 감사 대응 |
| 데이터 처리 | 대용량 보관 중심 | 스트림 분석 중심 | 혼합 처리 |
| 대표 한계 | 즉시 탐지 약함 | 장기 보관과 감사 한계 | 비용과 튜닝 부담 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Log Collection | 다양한 로그와 이벤트를 수집하는 공통 입력 계층으로 SIM과 SEM의 기반이 됨 |
| Archive and Search | 장기 저장과 조회와 보고서를 담당하는 SIM 성격의 보관 계층임 |
| Real-time Correlation | 시간 기반 규칙과 상관분석으로 즉시 경보를 생성하는 SEM 성격의 분석 계층임 |
| Unified Console | 두 기능의 결과를 단일 화면으로 보여주는 운영 계층으로 현대 SIEM의 사용자 접점임 |

```text
+-----------+    +----------------+    +----------------+    +----------------+
| Log/Event | -> | Archive/Search | -> | Correlation    | -> | Unified View   |
+-----------+    +----------------+    +----------------+    +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 로그 수집      | -> | 저장/인덱싱    | -> | 실시간 분석    | -> | 경보/보고서    | -> | 조사/개선      |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **로그 수집**: 다양한 시스템에서 이벤트를 모음
2. **저장과 인덱싱**: 장기 조회와 보고를 위해 보관함
3. **실시간 분석**: 규칙과 상관분석으로 즉시 탐지함
4. **경보와 보고서 생성**: 운영과 감사 목적의 산출물을 만듦
5. **조사와 개선**: 결과를 사건 조사와 룰 튜닝에 활용함

## Ⅵ. 실무 적용 및 유의점

1. 감사 요구 조직은 보관 기간과 고속 분석 대상을 분리하고 보관 비용·검색 시간·경보 지연으로 확인함
2. 신규 SIEM 도입은 컴플라이언스 로그와 실시간 보안 이벤트를 구분하고 use case 적중률·장기 보관 활용률로 확인함

## Ⅶ. 결론

- SIM과 SEM은 현대 SIEM의 뿌리이므로 저장 목적과 실시간 탐지 목적을 구분해야 과수집과 병목을 줄일 수 있음
