## Ⅰ. 개요
- **정의**: SIM은 보안 로그 장기 저장·분석, SEM은 실시간 이벤트 상관분석을 담당하며, 둘의 통합이 SIEM임
- **배경/필요성**: 로그 보관(컴플라이언스)과 실시간 탐지(사고 대응)는 목적이 다르므로 별도 기능으로 발전하였음
- **비유**: SIM은 은행의 거래 장부 보관소, SEM은 이상 거래 실시간 알림 시스템과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SIEM 구성 요소의 기원과 역할 구분 | SIM(저장/분석) + SEM(실시간 상관) = SIEM | SIM·SEM을 SIEM과 동일시하지 않도록 구분 필요 |

> 요약: SIM(로그 저장)과 SEM(실시간 상관)이 통합되어 SIEM으로 발전한 구조임

## Ⅱ. 구성요소
```text
[Log Sources] ---> [SIM: 저장/분석] --+
                                       +--> [SIEM 통합 뷰]
[Event Sources] -> [SEM: 실시간상관] --+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SIM 수집기 | 다양한 소스에서 로그를 수집·정규화·장기 저장함 | 도서관 아카이브 |
| SIM 분석기 | 저장된 로그를 대상으로 사후 포렌식·컴플라이언스 보고서 생성함 | 과거 거래 감사관 |
| SEM 상관엔진 | 실시간 이벤트 스트림에서 규칙 기반 상관분석을 수행함 | 실시간 이상 거래 감지기 |
| 통합 대시보드 | SIM·SEM 결과를 단일 화면에 통합 시각화함 | 통합 관제 모니터 |

> 요약: SIM(저장·포렌식)과 SEM(실시간 상관)이 통합 대시보드로 연결된 구조임

## Ⅲ. 절차
```text
수집 --> 분류 --> 분석 --> 통합
 |        |        |        |
 v        v        v        v
로그수집  SIM/SEM  상관/검색  대시보드
```
- 1단계: 수집 — 방화벽·서버·애플리케이션 로그를 에이전트 또는 Syslog로 수집함
- 2단계: 분류 — 수집된 데이터를 SIM(장기 저장 대상)과 SEM(실시간 분석 대상)으로 분류함
- 3단계: 분석 — SIM은 검색·보고서 생성, SEM은 상관 규칙 기반 실시간 탐지를 수행함
- 4단계: 통합 — 두 분석 결과를 통합 대시보드에 표시하고 알림·티켓을 생성함

> 요약: 로그 수집, SIM/SEM 분류, 각 엔진 분석, 통합 대시보드 표시 순서로 동작함

## Ⅳ. 문제점
- 데이터 이중 처리: SIM·SEM 별도 파이프라인 운영 시 동일 데이터 중복 적재 발생함
- 규칙 유지보수 부담: SEM 상관 규칙이 증가하면 규칙 간 충돌·오탐 관리 비용 증가함
- 확장성 한계: 로그 볼륨 급증 시 SIM 스토리지·SEM 처리 성능 동시 포화 가능함

> 요약: 데이터 중복, 규칙 유지보수, 확장성 한계가 주요 과제임

## Ⅴ. 개선방안
1. 단기: 통합 SIEM 플랫폼으로 전환하여 수집·분석 파이프라인 일원화 필요
2. 중기: ML 기반 상관분석 도입으로 수동 규칙 의존도 감소 필요
3. 장기: 클라우드 네이티브 SIEM(데이터 레이크 기반)으로 확장성 확보 필요

> 요약: 파이프라인 통합, ML 상관분석, 클라우드 SIEM 전환으로 단계적 개선 가능함

## Ⅵ. 전망
- 발전 방향: SIM·SEM 구분은 사라지고 SIEM(048 참조) 단일 플랫폼으로 완전 통합 중임
- 기술사적 판단: SOAR(049 참조)·XDR(053 참조)과 결합하여 통합 보안 운영 체계로 진화할 전망임
- 기술사 제언: 신규 도입 시 SIM·SEM 분리 아키텍처보다 통합 SIEM 기반 설계를 권장함
