## 미리 알고가기

- 데이터 오염은 학습 데이터에 악의적 샘플을 섞어 모델 행동을 왜곡하는 공격임
- 모델 탈취는 API나 파일을 통해 모델 파라미터나 동작 특성을 빼내 가는 공격임
- 프롬프트 인젝션은 입력 문장이나 외부 문서에 공격 지시를 숨겨 모델의 원래 지침을 흔드는 공격임

## Ⅰ. 개요

- **정의/개념**: AI 보안 위협 전체 구조는 데이터 수집, 모델 학습, 배포, 추론, 운영 단계의 침해 가능성을 생명주기로 묶어 보는 분류 체계임
- **배경/필요성**: AI 시스템은 데이터, 모델, 프롬프트 계층이 일반 IT 시스템 위에 추가됨. 기존 통제만으로는 공격 경로 설명이 부족함

## Ⅱ. 특징

- 데이터, 모델, 서비스, 사용자 입력이 모두 공격 표면이 됨
- 전통적인 계정 탈취와 공급망 위협에 AI 고유 위협이 겹쳐 나타남
- 학습 단계와 추론 단계의 위험 성격이 달라 통제 위치를 나눠 봐야 함
- 모델 성능 저하, 정보 유출, 서비스 오남용이 동시에 발생할 수 있음

## Ⅲ. 종류 및 비교

| 단계 | 대표 위협 | 주된 피해 |
|:---|:---|:---|
| 학습 단계 | 데이터 오염, 백도어 삽입, 학습 자산 변조 | 모델 품질 저하와 숨은 오동작 |
| 배포 단계 | 모델 파일 변조, 공급망 침해, 과도 권한 설정 | 악성 모델 배포와 운영 환경 노출 |
| 추론 단계 | 프롬프트 인젝션, 모델 탈취, 민감정보 유출 | 잘못된 응답, 데이터 유출, 도구 오남용 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 계층 | 수집 원천, 라벨링, 저장소, 전처리 경로가 공격 대상이 됨 |
| 모델 계층 | 가중치 파일, 파인튜닝 결과, 모델 레지스트리가 보호 대상임 |
| 서비스 계층 | API, 인증, 권한, 배포 파이프라인이 운영 노출을 좌우함 |
| 프롬프트·도구 계층 | 시스템 프롬프트, 외부 문서, 연결 도구가 추론 단계 공격면이 됨 |
| 모니터링 계층 | 이상 입력, 응답 유출, 비용 폭증을 감시함 |

```text
데이터 수집 -> 모델 학습 -> 모델 배포 -> 사용자 입력/도구 호출 -> 응답 생성 -> 모니터링·개선
```

## Ⅴ. 원리 및 절차 흐름도

```text
학습 자산 준비 -> 모델 생성 -> 배포 환경 연결 -> 사용자 입력 처리 -> 도구와 데이터 접근 -> 결과 검토와 차단
```

1. **학습 자산 준비**: 데이터와 코드와 모델 파일을 모음
2. **모델 생성**: 학습과 파인튜닝으로 결과 모델을 만듦
3. **배포 환경 연결**: API와 저장소와 도구 권한을 연결함
4. **입력 처리**: 사용자 입력과 외부 문서를 받아 추론함
5. **결과 검토**: 이상 응답과 정보 유출과 비용 급증을 감시함

## Ⅵ. 실무 적용 및 유의점

1. AI 서비스는 학습, 배포, 추론 단계를 나눠 통제하고 출처 확인 데이터 비율과 서명 검증 모델 배포 비율로 확인함
2. 외부 문서와 도구를 연결한 AI 서비스는 최소 권한과 출력 검토를 붙이고 과도 권한 도구 수와 민감정보 노출 재현 건수로 점검함

## Ⅶ. 결론

- AI 보안은 모델만 지키는 일이 아니라 데이터부터 도구 호출까지 이어지는 전체 경로를 나눠 보는 일이므로 단계별 공격면 구분이 출발점임
