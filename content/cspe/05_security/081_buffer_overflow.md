## 미리 알고가기

- 버퍼 오버플로우는 프로그램이 할당된 메모리 범위를 넘어 데이터를 기록해 인접 메모리를 오염시키는 취약점임
- 카나리는 덮어쓰기 탐지, DEP는 실행 차단, ASLR은 주소 예측 방해 역할을 맡는 보호 기법임
- 세 기법은 서로 다른 지점을 막으므로 하나만으로 충분하지 않고 함께 적용돼야 함

## Ⅰ. 개요

- **정의/개념**: 버퍼 오버플로우는 입력 길이 검증 실패로 버퍼 경계를 넘겨 메모리를 덮어쓰는 취약점이며, 카나리와 DEP와 ASLR은 그 결과가 제어 흐름 탈취로 이어지는 것을 줄이는 대표 방어 기법임
- **배경/필요성**: 메모리 안전성이 낮은 코드에서는 작은 입력 처리 실수도 원격 코드 실행과 권한 상승으로 이어질 수 있어 취약점 원리와 보호 기법의 역할을 함께 이해해야 함

## Ⅱ. 특징

- 취약점 자체는 입력 처리 실수에서 생기고 보호 기법은 피해 확산을 줄이는 보완 통제임
- 스택과 힙 모두 대상이 될 수 있으나 방어 적용 위치는 서로 다름
- 카나리와 DEP와 ASLR은 서로 다른 우회 기법을 상정하므로 다층 적용이 필요함
- 정보 유출 취약점과 결합되면 ASLR 우회가 가능해 테스트와 재검증이 중요함

## Ⅲ. 종류 및 비교

| 보호 기법 | 역할 | 한계 |
|:---|:---|:---|
| 스택 카나리 | 복귀 주소 앞의 변조를 탐지해 프로세스를 종료함 | 힙 오염이나 정보 유출 자체는 막지 못함 |
| DEP/NX | 데이터 영역 실행을 막아 주입 코드 실행을 차단함 | ROP 같은 코드 재사용 공격은 남을 수 있음 |
| ASLR | 메모리 배치를 무작위화해 주소 예측을 어렵게 함 | 정보 유출이 있으면 우회될 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 취약 버퍼 | 입력 데이터가 복사되는 메모리 공간임 |
| 제어 정보 | 복귀 주소, 함수 포인터, 객체 포인터 등 오염 시 위험한 값임 |
| 보호 기법 | 카나리, NX, ASLR, PIE 같은 컴파일·런타임 보호가 포함됨 |
| 검증 체계 | 정적 분석, 퍼징, 크래시 분석으로 취약 코드를 찾음 |

```text
입력 처리 실수 -> 버퍼 경계 초과 -> 제어 정보 오염 -> 보호 기법 개입 또는 실행 흐름 탈취
```

## Ⅴ. 원리 및 절차 흐름도

```text
취약 코드 존재 -> 과도한 입력 전달 -> 메모리 오염 -> 카나리/NX/ASLR 개입 -> 차단 또는 우회 시도
```

1. **취약 코드 존재**: 경계 검사 없는 복사나 조합 코드가 남아 있음
2. **과도한 입력 전달**: 공격자가 길거나 조작된 입력을 보냄
3. **메모리 오염**: 버퍼를 넘어 인접 메모리가 손상됨
4. **보호 기법 개입**: 카나리 탐지, NX 차단, ASLR 난수화가 동작함
5. **재검증**: 동일 입력으로 다시 실행 흐름 탈취가 가능한지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 시스템 프로그램과 에이전트는 카나리와 NX와 ASLR을 기본 빌드 옵션으로 두고, 안전 함수 전환과 퍼징을 함께 진행한 뒤 보호 옵션 적용률과 크래시 재현 여부와 취약 API 제거 상태로 확인함
2. 레거시 바이너리는 보호 옵션만 켠다고 끝나지 않으므로 정보 유출과 결합한 우회 시나리오까지 다시 시험하고 동일 익스플로잇 체인 차단 여부와 재빌드 후 보안 헤더 검증 결과로 확인함

## Ⅶ. 결론

- 버퍼 오버플로우 대응은 취약 코드 수정과 함께 카나리와 DEP와 ASLR을 겹쳐 적용해 우회 비용을 높이는 방향으로 설계해야 함
