## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 프로그램이 할당된 메모리 버퍼 크기를 초과하여 데이터를 기록할 때 인접 메모리를 덮어써 실행 흐름을 탈취하는 공격임 |
| **배경/필요성** | C/C++ 언어의 경계 검사 부재로 RCE(원격 코드 실행) 취약점이 지속 발생하며, 카나리·DEP·ASLR 등 다계층 방어가 필수임 |
| **출제 의도** | 스택/힙 오버플로우 원리와 방어 기법(카나리, DEP, ASLR) 간 상호 보완 관계를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
|  카나리   | --> |   DEP    | --> |  ASLR   |
| (Canary) |     | (NX Bit) |     | (주소랜덤)|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 스택 카나리 | 리턴 주소 앞에 삽입된 무작위 값으로, 변조 시 프로그램을 종료하여 RIP 탈취를 차단함 | 광산 카나리아가 가스를 감지하는 것 |
| DEP(NX Bit) | 데이터 영역(스택·힙)의 실행 권한을 제거하여 주입된 셸코드 실행을 차단함 | 주차장에서 운전 금지 구역 설정 |
| ASLR | 스택·힙·라이브러리 적재 주소를 매 실행마다 무작위 배치하여 공격자의 주소 예측을 방해함 | 매일 바뀌는 금고 비밀번호 |

> 요약: 카나리(변조 탐지), DEP(실행 차단), ASLR(주소 은닉)의 3중 방어로 오버플로우 공격을 억제함.

## Ⅲ. 절차
```
+------------+     +------------+
|  취약함수   | --> | 입력초과   |
|  호출      |     | 데이터삽입  |
+------------+     +------------+
                        |
+------------+     +----+-------+
| RIP 탈취   | <-- | 리턴주소   |
| 코드실행   |     | 덮어쓰기   |
+------------+     +------------+
```

1. 취약 함수 호출: `strcpy`, `gets` 등 경계 검사 없는 함수가 사용자 입력을 수신함
2. 버퍼 초과 기록: 할당된 버퍼 크기를 넘는 데이터가 스택 프레임의 인접 영역을 침범함
3. 리턴 주소 변조: 저장된 RIP(Return Instruction Pointer)가 공격자 지정 주소로 덮어써짐
4. 임의 코드 실행: 변조된 리턴 주소로 분기하여 셸코드 또는 ROP 가젯 체인이 실행됨

> 요약: 경계 미검사 → 인접 메모리 침범 → 리턴 주소 변조 → 임의 코드 실행 순으로 공격이 진행됨.

## Ⅳ. 문제점
- 레거시 코드 잔존: C/C++ 기반 레거시 시스템에 경계 미검사 함수(`gets`, `sprintf`)가 다수 잔존함
- 우회 기법 고도화: ROP·JOP·BROP 등으로 DEP·ASLR을 동시 우회하는 공격 기법이 진화함
- 힙 오버플로우 방어 한계: 스택 카나리는 힙 영역의 오버플로우를 탐지하지 못함

## Ⅴ. 개선방안
- (단기) 안전 함수 전환: `strncpy`, `snprintf` 등 경계 검사 함수로 레거시 코드를 교체함
- (중기) CFI 적용: Control Flow Integrity를 통해 ROP·JOP 가젯 체인의 비정상 분기를 차단함
- (장기) 메모리 안전 언어 전환: Rust·Go 등 메모리 안전 언어로 핵심 모듈을 점진 전환함

## Ⅵ. 전망
- CISA·NSA 공동 권고에 따라 메모리 안전 언어 채택이 가속화되며, 하드웨어 기반 메모리 태깅(ARM MTE)이 차세대 방어 표준으로 부상할 전망임
