## 미리 알고가기

- 모델 아티팩트는 학습된 가중치 파일, 설정 파일, 추론 코드처럼 배포에 쓰는 AI 산출물임
- 데이터 오염은 학습 데이터를 조작해 모델이 잘못된 판단을 하게 만드는 공격임
- AI-BOM은 AI Bill of Materials로, 모델과 데이터와 라이브러리의 출처와 구성 이력을 정리한 명세서임

## Ⅰ. 개요

- **정의/개념**: AI 공급망 보안은 외부 데이터셋, 사전학습 모델, 라이브러리, 학습 파이프라인처럼 AI 서비스가 의존하는 자산의 출처와 무결성과 사용 조건을 검증해 오염된 요소가 배포로 이어지지 않게 막는 보안 체계임
- **배경/필요성**: 생성형 AI와 오픈소스 모델 활용이 늘면서 직접 만든 코드보다 외부에서 가져오는 모델과 데이터가 더 많아졌고, 이 중 하나만 변조돼도 학습 환경과 서비스 전체가 함께 위험해질 수 있음

## Ⅱ. 특징

- 코드뿐 아니라 모델 파일, 데이터셋, 학습 도구까지 함께 관리해야 하므로 범위가 넓음
- 취약점 점검만으로는 부족하고 출처, 서명, 라이선스, 학습 이력까지 확인해야 함
- 학습 전 반입 통제와 배포 후 행위 감시가 같이 있어야 실제 공격을 줄일 수 있음
- 모델 성능이 좋아 보여도 백도어나 오염이 숨어 있을 수 있어 품질 검증과 보안 검증을 분리하지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 기존 소프트웨어 공급망 보안 | AI 공급망 보안 |
|:---|:---|:---|
| 주 관리 대상 | 패키지, 라이브러리, 빌드 산출물 | 모델, 데이터셋, 프롬프트 자산, 학습 파이프라인 |
| 대표 위험 | 취약한 오픈소스 의존성, 서명 없는 배포물 | 데이터 오염, 백도어 모델, 변조된 가중치 파일 |
| 주요 검증 방식 | SBOM, 서명 검증, 취약점 스캔 | AI-BOM, 서명 검증, 모델 스캔, 데이터 계보 점검 |
| 사고 영향 | 서비스 코드 취약점과 배포 오염 | 잘못된 응답, 은닉된 동작, 학습 환경 침해까지 확장됨 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 자산 출처 | 모델 허브, 데이터 저장소, 오픈소스 저장소처럼 외부 자산이 유입되는 시작 지점임 |
| 반입 검증 | 해시, 서명, 라이선스, 파일 형식, 악성 행위를 점검해 반입 가능 여부를 결정하는 단계임 |
| 신뢰 저장소 | 검증을 통과한 모델과 데이터만 내부 표준 위치에 보관해 임의 다운로드를 줄이는 저장소임 |
| 학습·배포 파이프라인 | 학습과 미세조정과 패키징 과정에서 승인된 자산만 쓰도록 강제하는 실행 경로임 |
| 운영 감시 | 배포 뒤 비정상 네트워크 호출, 예상 밖 출력, 정책 위반 동작을 감시하는 운영 계층임 |

```text
+-------------+    +-------------+    +-------------+    +-------------+
| 외부 자산 유입 | -> | 반입 검증      | -> | 신뢰 저장소    | -> | 학습/배포 파이프라인 |
+-------------+    +-------------+    +-------------+    +-------------+
       |
       v
+-------------+
| 운영 중 감시 |
+-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자산 수집      | -> | 출처 확인      | -> | 스캔/검사      | -> | 승인 저장      | -> | 배포 후 감시   |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자산 수집**: 외부 모델, 데이터, 도구를 반입 대상으로 등록함
2. **출처 확인**: 작성자, 서명, 해시, 라이선스, 버전 이력을 확인함
3. **스캔과 검사**: 악성 코드, 데이터 오염, 허용되지 않은 형식, 정책 위반 여부를 점검함
4. **승인 저장**: 검증을 통과한 자산만 내부 저장소에 올리고 파이프라인 사용 대상을 제한함
5. **배포 후 감시**: 운영 중 모델 동작과 호출 패턴을 살펴 이상 징후를 빠르게 차단함

## Ⅵ. 실무 적용 및 유의점

1. 오픈소스 모델을 업무망으로 들여올 때는 서명 검증과 샌드박스 로딩 검사를 거친 자산만 내부 레지스트리에 올리고 반입 승인율과 차단된 의심 자산 수로 운영 상태를 확인함
2. 외부 데이터로 미세조정할 때는 데이터 계보와 오염 점검 절차를 묶어 두고 이상 샘플 탐지율과 오염 의심 데이터 제거 시간을 함께 점검함

## Ⅶ. 결론

AI 공급망 보안은 모델 하나를 검사하는 일이 아니라 데이터와 모델과 파이프라인 전체의 신뢰를 관리하는 일이므로 반입 통제와 운영 감시를 함께 설계해야 함.
