## Ⅰ. 개요
- **정의**: 정보자산에 대한 위협·취약점을 분석하여 위험 수준을 산정하고 대응 우선순위를 결정하는 과정임
- **배경/필요성**: 제한된 보안 자원을 위험 수준이 높은 자산에 집중 배분하기 위해 정량적·정성적 위험 분석이 필요함
- **비유**: 건강검진으로 질병 위험도를 측정하여 치료 우선순위를 정하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 위험 평가 방법론 및 절차 | 자산-위협-취약점 삼각 관계, 정량적/정성적 분석 구분 | 위험(Risk)과 위협(Threat) 개념 혼동 주의 |

> 요약: 위험 평가는 자산-위협-취약점 분석을 통해 보안 투자의 우선순위를 결정하는 핵심 활동임

## Ⅱ. 구성요소
```text
[위험 평가 삼각 관계]
자산(Asset)
  |
  +-- 위협(Threat) ----> 위험(Risk) = 자산가치 x 위협 x 취약점
  |                        ^
  +-- 취약점(Vulnerability)-+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 자산 | 보호 대상 정보·시스템·인프라 | 금고 속 재산 |
| 위협 | 자산에 손실을 초래할 수 있는 외부/내부 요인 | 도둑·화재 |
| 취약점 | 위협이 악용 가능한 자산의 약점 | 잠금장치 결함 |
| 위험 수준 | 자산가치, 위협 가능성, 취약점 심각도의 조합으로 산정한 값 | 종합 위험 점수 |

> 요약: 자산·위협·취약점 세 요소의 조합으로 위험 수준을 산정함

## Ⅲ. 절차
```text
자산 식별 --> 위협/취약점 분석 --> 위험 수준 산정 --> 위험 처리 결정
```
- 1단계: 자산 식별 — 정보자산 목록을 작성하고 자산 가치(기밀성·무결성·가용성)를 평가함
- 2단계: 위협/취약점 분석 — 각 자산에 대한 위협 시나리오와 취약점을 식별·분석함
- 3단계: 위험 수준 산정 — 정량적(ALE = SLE x ARO) 또는 정성적(고/중/저) 방법으로 위험 수준을 산정함
- 4단계: 위험 처리 결정 — 수용·감소·전가·회피 중 적합한 처리 전략을 선택함(176 참조)

> 요약: 자산식별에서 위험처리 결정까지 4단계로 체계적 위험 분석을 수행함

## Ⅳ. 문제점
- 자산 목록 정체: 클라우드·컨테이너 환경에서 자산이 동적으로 변하나 정적 목록 관리로 누락 발생 — 실시간 파악이 어려움
- 정량화 한계: 위협 발생 확률과 손실 금액의 정확한 추정이 어려워 정량적 분석 신뢰도 저하 — 과거 데이터 부족이 원인임
- 평가 주기 문제: 연 1회 정기 평가로는 새로운 위협·취약점을 적시 반영하지 못함 — 위험 평가 결과가 빠르게 진부화됨

> 요약: 동적 자산 추적, 정량화 한계, 평가 주기 문제가 위험 평가의 정확성을 저해함

## Ⅴ. 개선방안
1. 단기: CMDB·클라우드 API 연동으로 자산 자동 탐지 및 실시간 목록 갱신 필요
2. 중기: EPSS·CVE 데이터 기반 위험 정량화 모델 도입으로 분석 신뢰도 향상 필요
3. 장기: 지속적 위험 평가(Continuous Risk Assessment) 체계로 전환하여 상시 모니터링 필요

> 요약: 자산 자동화, 데이터 기반 정량화, 지속적 평가로 위험 관리 정확성을 확보해야 함

## Ⅵ. 전망
- 발전 방향: AI 기반 위험 자동 산정 및 위협 인텔리전스 연계 실시간 위험 평가로 진화 예상됨
- 기술사적 판단: 위험 평가는 보안 의사결정의 근거이므로 정확성과 시의성이 생명임
- 기술사 제언: 정량적·정성적 분석을 상호 보완적으로 활용하되 데이터 기반 객관성을 강화해야 함
