## 미리 알고가기

- 가드레일은 모델이 해서는 안 되는 답변과 행동을 제한하는 안전 장치임
- 역할극 프롬프트는 다른 인물이나 상황을 가정하게 만들어 모델의 응답 방식을 바꾸는 입력임
- 다중 턴 대화는 여러 차례 대화를 이어 가며 제한을 서서히 무너뜨리는 방식임

## Ⅰ. 개요

- **정의/개념**: 탈옥 공격은 모델의 안전 규칙과 거부 정책을 우회하도록 입력을 설계해 금지 정보나 위험 절차를 끌어내는 프롬프트 공격임
- **배경/필요성**: LLM의 안전 통제도 자연어 규칙 위에 서 있음. 역할극, 우회 표현, 누적 대화가 들어오면 공격 문장을 더 강하게 따를 수 있음

## Ⅱ. 특징

- 목적이 넓은 행동 조작이 아니라 안전 거부 자체를 무너뜨리는 데 맞춰짐
- 단일 문장보다 역할극, 번역, 단계 분리 같은 우회 기법이 자주 쓰임
- 직접 유해 답변 생성뿐 아니라 후속 공격용 정보 수집으로 이어질 수 있음
- 프롬프트 보강만으로는 한계가 있어 학습, 평가, 출력 통제를 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 프롬프트 인젝션 | 탈옥 공격 |
|:---|:---|:---|
| 주된 목적 | 모델 행동 전반을 흔듦 | 안전 거부를 풀어 금지 답변을 끌어냄 |
| 흔한 기법 | 외부 문서 지시, 시스템 규칙 교란 | 역할극, 우회 표현, 다중 턴 설득 |
| 피해 범위 | 도구 오남용, 정보 유출, 응답 왜곡 | 유해 지식 노출, 안전 정책 무력화 |
| 방어 초점 | 입력 분리와 권한 제어 | 거부 일관성 강화와 공격 시나리오 평가 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 사용자 입력 | 우회 지시와 역할극을 담아 공격을 시작함 |
| 시스템 정책 | 모델이 지켜야 할 금지 규칙과 안전 기준임 |
| 안전 분류기 | 유해 요청과 금지 주제를 식별하는 계층임 |
| 모델 응답기 | 정책과 입력이 충돌할 때 최종 답변을 생성함 |
| 출력 차단기 | 위험한 답변을 다시 검사해 노출을 줄임 |

```text
공격 입력 -> 안전 분류기 -> 모델 응답기 -> 출력 차단기
                ^               |
                +--- 시스템 정책-+
```

## Ⅴ. 원리 및 절차 흐름도

```text
우회 입력 작성 -> 정책과 충돌 유도 -> 모델이 공격 문장 수용 -> 금지 답변 생성 시도 -> 출력 차단 또는 노출
```

1. **우회 입력 작성**: 공격자가 역할극이나 완곡한 표현을 섞어 질의함
2. **정책 충돌 유도**: 모델 안에 안전 규칙과 공격 지시가 함께 들어감
3. **공격 문장 수용**: 모델이 안전 규칙보다 공격 입력을 더 강하게 반영함
4. **위험 답변 생성 시도**: 금지된 정보나 절차를 설명하려 함
5. **차단 또는 노출**: 후단 검사가 약하면 그대로 노출될 수 있음

## Ⅵ. 실무 적용 및 유의점

1. 공개 챗봇과 사내 비서는 우회 표현과 다중 턴 설득 평가를 계속 돌리고 탈옥 성공률과 유해 응답 재현 건수로 점검함
2. 고위험 주제 서비스는 답변뿐 아니라 검색 결과와 도구 호출도 제한하고 차단된 고위험 요청 수와 승인 없는 외부 실행 건수로 확인함

## Ⅶ. 결론

- 탈옥 공격은 자연어 안전 규칙의 빈틈을 찌르는 입력 조작이므로 거부 일관성 평가와 후단 통제를 함께 설계해야 함
