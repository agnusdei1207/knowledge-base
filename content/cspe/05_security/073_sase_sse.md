## Ⅰ. 개요
- **정의**: 네트워크(SD-WAN)와 보안(SWG, CASB, ZTNA)을 클라우드 엣지에서 통합 제공하는 아키텍처
- **배경/필요성**: 원격근무와 SaaS 확산으로 본사 중심 보안 경계가 무의미해져 사용자 위치 무관한 보안 적용이 필요함
- **비유**: 어디서든 동일한 보안 검색을 받는 공항 보안 시스템과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 차세대 보안 아키텍처 | SASE = SD-WAN + SSE | SSE는 SASE의 보안 부분 집합임을 명시 |

> 요약: SASE는 네트워크와 보안을 클라우드 엣지에서 융합하여 위치 무관 보안을 구현함

## Ⅱ. 구성요소
```text
+-------------------+     +-------------------+
|    SD-WAN         |     |      SSE          |
| (네트워크 최적화) |     | SWG+CASB+ZTNA+FWaaS|
+-------------------+     +-------------------+
          |                         |
          +----------+--------------+
                     |
              클라우드 엣지 PoP
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SD-WAN | 다중 WAN 경로를 소프트웨어로 최적 선택/라우팅함 | 지능형 교통 관제 |
| SWG | 웹 트래픽 검사 및 URL/콘텐츠 필터링 수행(072 참조) | 출입 검색대 |
| CASB | SaaS 앱 사용 가시성 확보 및 정책 적용함 | 앱 사용 감독관 |
| ZTNA | 사용자/디바이스 신뢰도 기반 앱별 최소 접근 허용 | 1:1 호위 출입 |

> 요약: SD-WAN과 SSE(SWG+CASB+ZTNA)가 클라우드 PoP에서 통합 제공됨

## Ⅲ. 절차
```text
사용자 접속 --> 가장 가까운 PoP 연결 --> SSE 정책 검사 --> 앱/리소스 접근 허용
```
- 1단계: 사용자 접속 — 에이전트 또는 브라우저를 통해 SASE 플랫폼에 인증 요청함
- 2단계: PoP 연결 — 지리적으로 가장 가까운 클라우드 엣지 PoP에 트래픽을 라우팅함
- 3단계: SSE 정책 검사 — SWG, CASB, ZTNA, DLP 정책을 PoP에서 인라인 적용함
- 4단계: 앱 접근 허용 — 정책 통과 시 SD-WAN 최적 경로로 대상 앱에 연결함

> 요약: 인증-PoP 연결-보안 검사-최적 경로 연결의 4단계로 사용자별 보안 접근을 제공함

## Ⅳ. 문제점
- PoP 의존성: 가까운 PoP가 없는 지역에서 지연이 증가하여 사용자 경험이 저하됨
- 벤더 성숙도: 네트워크+보안 전 기능을 단일 벤더가 균등하게 제공하기 어려움
- 전환 복잡성: 기존 VPN, 방화벽, 프록시 인프라에서 SASE로의 마이그레이션이 복잡함

> 요약: PoP 커버리지, 벤더 역량 편차, 전환 복잡성이 SASE 도입의 장애 요인임

## Ⅴ. 개선방안
1. 단기: PoP 커버리지가 넓은 벤더를 선정하고 지연 임계값 기반 SLA를 계약함
2. 중기: 네트워크(SD-WAN)와 보안(SSE)을 분리 도입 후 점진적으로 통합함
3. 장기: 레거시 VPN/방화벽을 단계적으로 퇴역시키며 ZTNA 기반 접근으로 전환함

> 요약: SLA 기반 벤더 선정, 점진적 통합, 레거시 퇴역으로 SASE 전환을 안정화함

## Ⅵ. 전망
- 발전 방향: AI 기반 트래픽 분석과 자동 정책 조정이 SASE 플랫폼에 내장될 전망
- 기술사적 판단: SASE는 네트워크+보안의 수렴 종착점으로, 하이브리드 근무 환경의 표준 아키텍처가 될 것임
- 기술사 제언: SSE부터 도입하여 보안 가치를 조기에 확보한 후 SD-WAN 통합을 추진하는 단계적 전략이 필요함
