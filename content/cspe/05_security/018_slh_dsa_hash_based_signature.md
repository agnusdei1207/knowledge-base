# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **SLH-DSA는 해시함수 안전성에만 기반한 NIST FIPS 205 무상태(stateless) 전자서명 표준으로, 격자 서명(ML-DSA)의 알고리즘 다양성을 보완함**. 양자위협·PQC 전반은 (015 참조).
- **왜 필요한가**: 격자 서명 ML-DSA(017)에 훗날 구조적 결함이 발견될 경우를 대비해, 전혀 다른 근거(해시)의 백업 서명이 필요하기 때문임 — 한 난제에 전부 걸지 않으려는 것임.
- **핵심 직관**: 거대한 일회용 도장 묶음을 해시 트리(Merkle)로 봉인해 두고, 서명할 때마다 "이 도장이 트리에 속한다"는 경로 증거를 붙여 검증하게 함 — 상태를 저장하지 않아도 재사용 사고가 안 남.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안(Ⅰ~Ⅵ·표)에 나오는 표기·구조를 비유와 함께 먼저 풀어 둠. 상위 핵심 키워드는 **해시 기반 서명(hash-based signature)** 으로, 오직 해시함수의 일방향성·충돌저항에만 안전성을 두는 방식임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 해시 기반 서명 | 해시함수 안전성에만 의존하는 서명 | 도장을 해시 도장으로만 제작 |
| stateless(무상태) | 서명 횟수 상태를 저장하지 않아도 됨 | 사용 이력 장부 관리 불필요 |
| WOTS+ | 해시 체인 기반 일회성 서명 | 한 번만 쓰는 낱개 도장 |
| FORS | digest 일부에 대한 few-time 서명 | 몇 번 쓰는 색인 도장 묶음 |
| Merkle tree | 해시로 여러 값을 루트 하나로 봉인 | 낱장을 묶어 한 표지로 봉함 |
| hypertree | Merkle tree를 여러 계층 쌓은 구조 | 트리의 트리(다층 색인) |
| 인증 경로 | 리프에서 루트까지의 해시 증거 | 서가 위치 증명 경로 |
| SLH-DSA-{SHA2/SHAKE}-{128/192/256}{s/f} | 해시·강도·소형(s)/고속(f) 파라미터 | 도장 등급·소형/고속 선택 |
| LMS/XMSS | 상태 관리형 해시 서명(상태 유실 시 위험) | 장부 필수인 구형 해시 도장 |
| dual-sign | ML-DSA와 함께 서명 병용 | 격자 도장 + 해시 도장 |

## 깊이 이해
- **배경·문제의식**: 해시 기반 서명은 오래 연구된 보수적 PQC 계열임. 다만 상태 관리형 LMS/XMSS는 "몇 번째 일회용 키를 썼는지" 상태를 잃으면 키 재사용으로 치명적 위조가 생김. SLH-DSA는 상태 저장 없이 서명해 운영 오류 위험을 없앰. 원래 공모명은 SPHINCS+, 2024년 8월 FIPS 205로 확정됨.
- **작동 원리(어떻게+왜)**: 메시지를 해시해 얻은 digest를 FORS(few-time)로 서명하고, 그 FORS 공개값을 WOTS+로 서명하며, 이를 hypertree 여러 계층으로 이어 최상위 공개키 루트에 연결함. 검증자는 서명에 담긴 인증 경로를 해시로 재계산해 공개키 루트와 일치하는지만 봄 — 안전성이 오직 해시에 있어 격자 결함과 무관함.
- **비유**: 도서관 색인 카드 묶음을 해시로 봉인해 두고, 특정 책을 증명할 때 책 카드(FORS)와 서가 경로(hypertree 경로)를 함께 제시하는 것과 같음.
- **구체 예시**: SLH-DSA 서명은 파라미터에 따라 약 7.9KB(128s)~49.9KB(256f)로 매우 큼(ML-DSA-65 3309B의 수배~십수 배). 그래서 고빈도 TLS보다 루트 CA·펌웨어 마스터키·오프라인 서명에 적합함.
- **흔한 오해·주의점**: (1) SLH-DSA는 서명이 작아서 쓰는 게 아님 — 오히려 큼. 보수적 해시 안전성과 무상태 운영이 핵심 가치임. (2) LMS/XMSS와 달리 상태 관리가 불필요함. (3) KEM·QKD와 혼동 금지 — 서명 알고리즘임.

## 연결 개념
- ML-DSA — SLH-DSA가 보완하는 1순위 격자 서명 (017 참조)
- 해시 알고리즘 — SLH-DSA 안전성의 유일한 근거(SHA2/SHAKE) (004 참조)
- LMS/XMSS — 상태 관리형 해시 서명, 상태 유실 위험으로 대비됨

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLH-DSA는 SPHINCS+ 기반 NIST FIPS 205 무상태 해시 기반 전자서명 표준임.
> 2. **가치**: 오직 해시함수 안전성에 의존해 격자 서명 ML-DSA의 알고리즘 다양성 백업을 제공함.
> 3. **판단 포인트**: 서명 크기 7.9KB~49.9KB·검증 지연·무상태 장점을 근거로 루트 CA·펌웨어 등 저빈도 자산에 적용함이 관건임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PQC 서명 다양성 이해 | FIPS 205·해시 기반·stateless | ML-DSA와 같은 격자 기반으로 서술 |
| 구조·운영 판단 | FORS·WOTS+·hypertree·큰 서명 | 작은 서명·고빈도 TLS 용도만 강조 |
| 적용처 선별 | root CA·펌웨어·오프라인 서명 | KEM·QKD와 혼동 |

> 요약: SLH-DSA 답안은 해시 기반·무상태·큰 서명·보수적 백업 서명이라는 판단축을 정확히 보여야 함.

## Ⅰ. 개요 및 필요성

- 개요: 해시함수 안전성에만 기반한 무상태 양자내성 서명임.
- 배경: PQC 전환을 단일 격자 난제에 집중하면 취약점 발견 시 인증서·코드서명 공급망 영향이 큼(015·017).
- 필요성: NIST FIPS 205 표준으로 해시 기반 서명을 제공해 인증·무결성·부인방지의 알고리즘 다양성을 확보함.
- 전제: 양자위협·PQC 개괄은 (015 참조), 격자 서명은 (017 참조)로 위임하고 해시 기반 무상태 서명에 집중함.

---

## Ⅱ. 구조 및 구성요소

```text
Message -> Hash(digest) -> FORS 서명
FORS 공개값 -> WOTS+ 서명 -> hypertree 인증 경로
Signature + 공개키(root) -> Verify -> Accept/Reject
  / Stateless Signing -> 상태 저장 오류 원천 제거
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Hash function | 메시지 축약·트리 노드 계산 | SHA2 또는 SHAKE 파라미터 |
| FORS | digest 일부에 대한 few-time 서명 | 서명 크기 증가 요인 |
| WOTS+ | 해시 체인 기반 일회성 서명 | 계층별 루트 연결 |
| hypertree | 여러 Merkle tree 계층 결합 | 공개키 루트로 검증 |

> 요약: SLH-DSA는 FORS·WOTS+·hypertree를 해시함수로 연결해 상태 저장 없이 서명을 생성함.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성(root 공개키) -> 메시지 해시 -> FORS 서명
  -> WOTS+ 계층 서명 -> 인증 경로 첨부
  -> 검증자 공개키 root 비교 -> 서명 검증 -> 감사 기록
```

1. 발급자가 KeyGen으로 hypertree 최상위 root 공개키와 seed 기반 개인키를 생성함.
2. 서명자가 메시지 digest를 FORS로, FORS 공개값을 WOTS+로 서명하고 hypertree 인증 경로를 첨부함.
3. 검증자가 인증 경로를 해시로 재계산해 공개키 root와 일치하면 accept, 아니면 reject를 냄.
4. 서명자 ID·시각·검증 결과를 로그에 남겨 릴리스 증적을 확보함.

> 요약: 메시지 digest를 해시 트리 경로로 증명하고, 공개키 루트와 일치하면 서명을 승인하며 증적을 남김.

---

## Ⅳ. 특징

- 해시 단일 근거: 안전성이 오직 해시함수(SHA2/SHAKE)에 있어 격자 결함과 무관한 보수적 서명임.
- 무상태 운영: 서명 횟수 상태를 저장하지 않아 LMS/XMSS의 상태 유실·키 재사용 사고를 원천 회피함.
- 큰 서명 크기: 서명이 7.9KB~49.9KB로 매우 커 대역폭·저장소·검증 지연 부담이 큼.
- 파라미터 트레이드오프: s(소형·느린 서명)와 f(고속·큰 서명) 중 용도별로 고정 선택해야 함.
- 백업 위치: 1순위 범용 서명(ML-DSA)이 아니라 저빈도·고가치 자산의 보완 서명으로 배치함.
- 표준 확립: 2024년 FIPS 205 확정으로 KAT·ACVP 적합성 검증 근거가 있음.

## Ⅴ. 심화 비교 및 적용 판단

같은 PQC 서명인 ML-DSA(격자)와 SLH-DSA(해시)를 안전근거·크기·운영 축으로 비교함(다대상×다축이므로 표 사용).

| 구분 | ML-DSA-65(격자) | SLH-DSA(해시) |
|:---|:---|:---|
| 안전 근거 | 격자 Module-LWE/SIS | 해시함수(SHA2/SHAKE) |
| 서명 크기 | 3309B | 약 7.9KB~49.9KB |
| 서명/검증 속도 | 빠름(범용) | 느림(다수 해시) |
| 상태 관리 | 불필요 | 불필요(무상태) |
| 역할 | PQC 1순위 범용 서명 | 보수적 백업·다양성 |

> 요약: SLH-DSA는 크기·속도를 감수하는 대신 격자와 독립된 안전 근거를 얻으므로, ML-DSA를 대체가 아닌 보완으로 배치함.

리스크는 불릿으로 정리함.
- 리스크: 서명 비대화 — 원인: FORS/WOTS+ 인증 경로 포함 — 대응: offline signing·압축/분할 배포, 패키지 증가율 5% 이하.
- 리스크: 검증 지연 — 원인: 다수 해시 연산 — 대응: 검증 캐시·release pipeline 병렬화, 검증 p95 SLA 충족.
- 리스크: 파라미터 오선택 — 원인: security level·s/f 혼선 — 대응: 정책 프로파일 고정, 승인 외 파라미터 0건.

지표는 불릿으로 정리함.
- 지표: 표준 적합성 — 목표: FIPS 205 KAT 100% 통과 — 측정: ACVP·테스트 벡터.
- 지표: 적용 적합성 — 목표: 서명 빈도·파일 크기 영향 산정 — 측정: 릴리스 패키지 측정.
- 지표: 검증 통제 — 목표: 변조 서명 reject 100% — 측정: CI negative test·감사로그.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 루트 CA·펌웨어 master key·장기 보관 문서처럼 서명 빈도는 낮고 검증 기간은 10년↑인 자산부터 후보 지정.
2. ML-DSA와 SLH-DSA dual-sign 정책을 수립하고 패키지 크기 증가율 5% 이하·검증 p95 SLA를 배포 전 측정.
3. FIPS 205 KAT·키 seed HSM 보관·signer ID/timestamp/검증 결과 로그를 릴리스 파이프라인에 통합.

**결론 (2줄):**
- 기술사 판단: SLH-DSA는 범용 1순위 서명보다 보수적 백업 서명으로 가치가 크며, 저빈도·장기 검증 자산에 적용함.
- 향후 방향: ML-DSA 중심 전환에 SLH-DSA를 보완 계층으로 배치해 PQC 알고리즘 다양성을 확보해야 함.
