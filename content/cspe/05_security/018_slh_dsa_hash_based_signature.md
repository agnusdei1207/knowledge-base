## 미리 알고가기

- 해시 기반 서명: 해시 함수의 일방향성과 충돌 저항성을 서명 검증 근거로 쓰는 방식임
- Stateless: 서명 횟수 상태를 따로 저장하지 않아 분산 환경에서도 상태 동기화 문제가 없는 구조임
- FORS: 여러 작은 트리를 묶어 메시지별 서명 경로를 만드는 구성 요소임
- Hypertree: 여러 머클 트리를 계층적으로 연결해 많은 서명을 처리하는 구조임

## Ⅰ. 개요

- **정의/개념**: SLH-DSA는 해시 함수 기반의 stateless PQC 전자서명 표준임. 장기 보존 서명에 활용함
- **배경/필요성**: 격자 기반 서명과 다른 안전성 가정을 가진 대안이 필요함. 해시 함수 성질에 기반한 서명 체계가 그 역할을 담당함

## Ⅱ. 특징

- 해시 함수 성질에 의존해 격자 기반 서명과 안전성 가정이 다름
- 상태를 저장하지 않아 stateful 서명의 카운터 동기화 문제를 줄임
- 공개키는 작지만 서명 크기가 커 대량 전송에는 부담이 큼
- 장기 보존 문서, 루트 신뢰점, 펌웨어 같은 고보수 환경에 맞음

## Ⅲ. 종류 및 비교

| 판단 기준 | XMSS/LMS | SLH-DSA |
|:---|:---|:---|
| 상태 관리 | 서명할 때마다 상태를 정확히 갱신해야 하며 백업 불일치가 서명 키 재사용 위험을 만듦 | 상태를 별도로 저장하지 않아 분산 운영과 복구 절차가 단순함 |
| 서명 크기 | 비교적 작게 설계할 수 있으나 상태 관리 부담이 뒤따름 | 서명 크기가 커지지만 상태 동기화 문제를 줄일 수 있음 |
| 운영 난이도 | 서명 서버 이중화와 백업 절차가 까다로움 | 다중 인스턴스 배포와 자동화가 상대적으로 단순함 |
| 적합한 환경 | 상태를 엄격히 통제할 수 있는 전용 서명 장비에 맞음 | 장기 보존과 분산 운영을 함께 요구하는 환경에 맞음 |

> 요약: XMSS/LMS는 서명 크기가 작지만 상태 관리가 어렵고, SLH-DSA는 크기 부담이 있는 대신 stateless 운영에 맞음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 해시 함수 | 충돌 저항성과 일방향성을 제공하는 기반 함수이며, 해당 성질이 약해지면 서명 검증 근거도 약해짐 |
| FORS | 메시지에 따라 여러 작은 트리 경로를 선택해 서명 재료를 만드는 부분이며, 메시지별 다양성을 담당함 |
| Hypertree | 여러 단계의 머클 트리를 이어 많은 서명을 처리하도록 확장하는 구조이며, 최종 공개키 루트까지 경로를 연결함 |
| 서명값 | FORS 정보와 인증 경로를 함께 담는 결과물이며, 이 경로 정보 때문에 서명 크기가 크게 늘어남 |

```text
+--------+     +------+     +-----------+     +--------+
| 메시지 | --> | FORS | --> | Hypertree | --> | 서명값 |
+--------+     +------+     +-----------+     +--------+
                                          |
                                   +-------------+
                                   | 루트 공개키 |
                                   +-------------+
```

> 요약: 메시지별 FORS 서명과 계층형 머클 경로를 묶어 공개키 루트까지 검증하는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+----------+     +-------------+     +-------------+     +----------+     +----------+
| 키 생성  | --> | 메시지 난수화 | --> | FORS 경로 생성 | --> | 트리 경로 결합 | --> | 공개키 검증 |
+----------+     +-------------+     +-------------+     +----------+     +----------+
```

1. **키 생성**: 루트 공개키와 비밀 시드를 생성함
2. **메시지 난수화**: 메시지에 난수 요소를 섞어 서명 입력을 안정화함
3. **FORS 경로 생성**: 메시지에 대응하는 잎사귀와 인증 경로를 선택함
4. **트리 경로 결합**: 상위 하이퍼트리 경로를 붙여 루트까지 연결함
5. **공개키 검증**: 검증자가 루트 공개키까지 경로를 재계산해 확인함

## Ⅵ. 실무 적용 및 유의점

1. 루트 CA·장기 문서·펌웨어 서명은 SLH-DSA가 보수적 선택이며 저장소 용량·배포 시간·검증 지연으로 확인함
2. 다중 인스턴스 서명은 stateless 장점이 크나 해시 비용이 높으므로 병렬화·캐시와 초당 서명 수를 관리함

## Ⅶ. 결론

- SLH-DSA는 서명 크기 비용을 감수하더라도 장기 보존성과 해시 기반 안전성 가정을 우선할 때 선택하는 PQC 서명 대안임

## 작성 근거(검토용)

- 범위가 넓은 표현을 해시 성질, 상태 갱신, 키 재사용 위험으로 바꿈
- XMSS/LMS와 비교한 이유는 SLH-DSA의 stateless 특성이 가장 잘 드러나는 대비이기 때문임
- 결론은 “보수적”이라는 평가만 남기지 않고 서명 크기 비용과 해시 기반 가정을 함께 제시함
