# 📖 【암기용】 개념 완전 이해

> 목적: SLH-DSA 해시 기반 서명을 처음 봐도 완전하게 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 해시 함수 안전성에 기반한 NIST FIPS 205 무상태 전자서명
- **왜 필요한가**: 격자 기반 서명에 구조적 취약점이 발견될 경우를 대비해 해시 함수 기반 대체 서명 표준이 필요하다. SLH-DSA는 다중 서명 상태를 저장하지 않는 SPHINCS+ 계열 표준이다.
- **핵심 직관**: 거대한 일회용 도장 묶음을 해시 트리로 정리해 두고, 서명할 때마다 경로 증거를 붙여 검증하게 하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 해시 기반 서명은 오래 연구된 PQC 계열이지만 상태 관리형 LMS/XMSS는 서명 횟수 상태를 잃으면 키 재사용 문제가 발생한다. SLH-DSA는 상태 저장 없이 서명할 수 있어 운영 오류 위험을 낮춘다.
- **작동 원리**: 메시지 해시, FORS, WOTS+, hypertree 구조로 서명을 생성한다. 검증자는 공개키의 루트 값과 서명 경로를 비교해 메시지와 서명의 일관성을 확인한다.
- **비유**: 도서관 색인 카드 여러 묶음을 해시로 봉인해 두고, 특정 책을 증명할 때 책 카드와 서가 경로를 함께 제시하는 것과 같다.
- **구체 예시**: SLH-DSA 서명은 파라미터에 따라 약 7.9KB에서 49.9KB까지 커질 수 있어 TLS 인증서보다 코드서명·펌웨어 서명 백업 용도에 적합하다.
- **흔한 오해·주의점**: SLH-DSA는 서명 크기가 작아서 쓰는 기술이 아니다. 보수적인 해시 기반 안전성과 무상태 운영이 핵심 가치이다.

## 연결 개념
- FIPS 205 — SLH-DSA 표준 문서
- ML-DSA — 일반 목적 격자 기반 서명 표준
- LMS/XMSS — 상태 관리형 해시 기반 서명

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLH-DSA는 SPHINCS+ 기반의 NIST FIPS 205 무상태 해시 기반 전자서명 표준임.
> 2. **가치**: 해시 함수 안전성에 기반하여 격자 기반 ML-DSA의 알고리즘 다양성 보완 수단을 제공함.
> 3. **판단 포인트**: 서명 크기 7.9KB~49.9KB, 검증 지연, 무상태 장점, 코드서명·루트 서명 적용성을 비교해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PQC 서명 다양성 이해 | FIPS 205, hash-based, stateless | ML-DSA와 같은 격자 기반으로 서술 금지 |
| 구조·운영 판단 | FORS, WOTS+, hypertree, 큰 signature | 작은 서명·고빈도 TLS 용도만 강조 금지 |
| 적용처 선별 | root CA, firmware, offline signing | QKD나 KEM과 혼동 금지 |

> 요약: SLH-DSA 답안은 해시 기반·무상태·큰 서명 크기·보수적 백업 서명이라는 판단축을 보여야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 해시 기반 상태 비저장 서명
- 배경: PQC 전환을 단일 수학 난제에 집중하면 알고리즘 취약점 발견 시 인증서·코드서명 공급망 영향이 커짐.
- 필요성: SLH-DSA는 NIST FIPS 205 표준으로 해시 함수 기반 전자서명을 제공해 인증·무결성·부인방지의 알고리즘 다양성을 확보함.

---

## Ⅱ. 구조 및 구성요소

```text
Message -> Hash -> FORS 서명
FORS root -> WOTS+ 서명 -> Hypertree 인증 경로
Signature + Public Key -> Verify -> Accept/Reject
/ Stateless Signing -> 상태 저장 오류 제거
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Hash function | 메시지 축약·트리 노드 계산 | SHA2 또는 SHAKE 기반 파라미터 |
| FORS | 메시지 digest 일부에 대한 few-time 서명 | 서명 크기 증가 요인 |
| WOTS+ | 해시 체인 기반 일회성 서명 | 트리 계층별 루트 연결 |
| Hypertree | 여러 Merkle tree 계층 결합 | 공개키 루트 검증 |

> 요약: SLH-DSA는 FORS, WOTS+, hypertree를 해시 함수로 연결해 상태 저장 없이 서명을 생성함.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성 -> 메시지 해시 -> FORS 서명 생성
-> WOTS+ 계층 서명 -> 인증 경로 첨부
-> 공개키 root 비교 -> 서명 검증 -> 감사 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 공개키·개인키 생성 | FIPS 205 KAT, seed 관리 |
| 2 | 메시지 digest 산출 | domain separation, context binding |
| 3 | FORS/WOTS+ 서명 생성 | 서명 크기 파라미터 확인 |
| 4 | Hypertree 경로 검증 | 공개키 root 일치 |
| 5 | 서명 로그 보관 | signer ID, timestamp, 검증 결과 |

> 요약: SLH-DSA는 메시지 digest를 해시 트리 경로로 증명하고 공개키 루트와 일치하면 서명을 승인함.

---

## Ⅳ. 특징

| 구분 | ML-DSA | SLH-DSA | 판단 포인트 |
|:---|:---|:---|:---|
| 기반 난제 | 모듈 격자 | 해시 함수 | 알고리즘 다양성 |
| 표준 | FIPS 204 | FIPS 205 | 백업·보수적 서명 |
| 서명 크기 | ML-DSA-65 3309B | 약 7.9KB~49.9KB | 대역폭·저장소 영향 |
| 운영 상태 | 일반 서명 | 무상태 해시 서명 | LMS/XMSS 상태 오류 회피 |

> 요약: SLH-DSA는 크기 비용을 감수하고 해시 기반 안전성과 무상태 운영을 확보하는 PQC 서명 보완재임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | LMS/XMSS 상태형 | SLH-DSA 무상태 | 상태 동기화가 어려운 배포망 |
| 비용/성능 | ECDSA 64B 서명 | KB급 서명 | 저빈도·고가치 서명 |
| 운영/위험 | ML-DSA 단일 계열 | 해시 기반 대체 | 알고리즘 리스크 분산 |

> 요약: SLH-DSA는 고빈도 TLS보다 루트 CA, 펌웨어 릴리스, 장기 보관 서명에 우선 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 서명 비대화 | FORS/WOTS+ 인증 경로 포함 | offline signing, 압축·분할 배포 | 패키지 증가율 5% 이하 |
| 검증 지연 | 다수 해시 연산 | 검증 캐시, release pipeline 병렬화 | 검증 p95 SLA 충족 |
| 파라미터 오선택 | security level·s/f 선택 오류 | 정책 프로파일 고정 | 승인 외 파라미터 0건 |

> 요약: SLH-DSA 리스크는 크기, 검증 지연, 파라미터 선택이며 배포 대상별 프로파일로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표준 적합성 | FIPS 205 KAT 100% 통과 | ACVP, test vector |
| 적용 적합성 | 서명 빈도·파일 크기 영향 산정 | 릴리스 패키지 측정 |
| 검증 통제 | 변조 signature reject 100% | CI negative test, 감사로그 |

> 요약: SLH-DSA 도입은 FIPS 검증, 크기 영향, 위조 서명 차단 지표로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 루트 CA, 펌웨어 master key, 장기 보관 문서처럼 서명 빈도는 낮고 검증 기간은 10년 이상인 자산부터 후보 지정.
2. ML-DSA와 SLH-DSA dual-sign 정책을 수립하고 패키지 크기 증가율 5% 이하, 검증 p95 SLA를 배포 전 측정.
3. FIPS 205 KAT, 키 seed HSM 보관, signer ID·timestamp·검증 결과 로그를 릴리스 파이프라인에 통합.

**결론 (2줄):**
- 기술사 판단: SLH-DSA는 일반 목적 1순위 서명보다 보수적 백업 서명으로 가치가 크며, 저빈도·장기 검증 자산에 적용함.
- 향후 방향: ML-DSA 중심 전환에 SLH-DSA를 보완 계층으로 배치하여 PQC 알고리즘 다양성을 확보해야 함.
