## Ⅰ. 개요
- **정의**: 클라우드 서비스에서 CSP와 고객 간 보안 책임 영역을 서비스 모델별로 분담하는 프레임워크임
- **배경/필요성**: 클라우드 전환 시 보안 책임 경계가 모호하여 사각지대가 발생하므로 역할 분담 기준이 필요함
- **비유**: 임대 아파트에서 건물 구조는 건물주, 내부 인테리어는 세입자가 관리하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IaaS/PaaS/SaaS별 책임 경계 이해 | 서비스 모델에 따라 고객 책임 범위가 변동됨 | "CSP가 모두 책임"이라는 오해 방지 |

> 요약: 공동 책임 모델은 서비스 모델별로 CSP와 고객 간 보안 책임 영역을 명확히 분담하는 체계임

## Ⅱ. 구성요소
```text
       IaaS        PaaS        SaaS
      ------      ------      ------
App  : 고객       고객        CSP
Data : 고객       고객        고객
Runtime: 고객     CSP         CSP
OS   : 고객       CSP         CSP
Infra: CSP        CSP         CSP
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CSP 책임 영역 | 물리 인프라, 네트워크, 하이퍼바이저 등 기반 계층 보호 | 건물 골조 관리 |
| 고객 책임 영역 | 데이터 암호화, 접근 제어, 애플리케이션 보안 등 상위 계층 보호 | 실내 보안 관리 |
| 공유 책임 영역 | 패치 관리, 네트워크 구성 등 CSP와 고객이 협력하는 영역 | 공용 현관 관리 |
| 서비스 모델 | IaaS/PaaS/SaaS에 따라 책임 경계선이 상하로 이동함 | 전세/반전세/호텔 |

> 요약: CSP 기반 계층, 고객 상위 계층, 공유 영역으로 나뉘며 서비스 모델에 따라 경계가 변동됨

## Ⅲ. 절차
```text
서비스 모델 선정 -> 책임 경계 식별 -> 보안 통제 구현 -> 지속 모니터링
```
- 1단계: 조직의 워크로드에 적합한 클라우드 서비스 모델(IaaS/PaaS/SaaS)을 선정함
- 2단계: CSP의 공동 책임 매트릭스를 기준으로 고객 책임 영역을 식별함
- 3단계: 식별된 고객 책임 영역에 암호화, IAM, 네트워크 정책 등 보안 통제를 구현함
- 4단계: CSPM(117 참조) 등 도구로 설정 오류와 책임 공백을 지속적으로 모니터링함

> 요약: 모델 선정, 경계 식별, 통제 구현, 모니터링의 4단계로 공동 책임을 이행함

## Ⅳ. 문제점
- 책임 경계 오인: 고객이 CSP 책임으로 착각하여 데이터 암호화·접근 제어를 누락함
- 멀티 클라우드 복잡성: CSP마다 책임 매트릭스가 상이하여 일관된 보안 정책 적용이 어려움
- 가시성 부재: 고객이 CSP 내부 인프라 상태를 직접 확인할 수 없어 신뢰 검증이 제한됨

> 요약: 경계 오인, 멀티 클라우드 복잡성, 가시성 부재가 공동 책임 이행의 주요 장벽임

## Ⅴ. 개선방안
1. 단기: CSP별 공동 책임 매트릭스를 문서화하고 보안 체크리스트에 반영함
2. 중기: CNAPP(119 참조) 통합 플랫폼으로 멀티 클라우드 환경의 보안 정책을 일원화함
3. 장기: CSP 투명성 보고서와 제3자 감사(SOC 2, ISO 27001)를 통해 가시성을 확보함

> 요약: 매트릭스 문서화, 통합 플랫폼, 제3자 감사로 공동 책임 이행 체계를 강화해야 함

## Ⅵ. 전망
- 발전 방향: AI/데이터 서비스 확산으로 모델 학습 데이터·추론 결과에 대한 책임 분담 논의가 확대될 전망임
- 기술사적 판단: 공동 책임 모델은 클라우드 보안 거버넌스의 출발점으로 중요성이 지속될 것임
- 기술사 제언: 클라우드 도입 시 계약 단계에서 SLA와 책임 매트릭스를 명시적으로 합의해야 함
