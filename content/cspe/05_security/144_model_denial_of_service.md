## 미리 알고가기

- 컨텍스트 윈도우는 모델이 한 번에 읽고 기억할 수 있는 입력 길이 범위임
- 출력 토큰은 모델이 한 번의 응답에서 생성하는 단어 조각 수를 뜻함
- 자기 주의 연산은 입력 길이가 길어질수록 계산량이 크게 늘 수 있는 LLM 핵심 연산임

## Ⅰ. 개요

- **정의/개념**: 모델 DoS는 길거나 계산이 무거운 입력으로 추론 자원과 응답 시간을 비정상적으로 늘려 LLM 서비스 가용성을 떨어뜨리는 공격임
- **배경/필요성**: LLM은 적은 요청만으로도 GPU, 메모리, 토큰 비용이 크게 늘 수 있음. 입력 자체가 새로운 공격 자원이 됨

## Ⅱ. 특징

- 대량 트래픽보다 고비용 질의 몇 개가 더 큰 피해를 만들 수 있음
- 응답 지연뿐 아니라 과금 폭증과 자동 확장 남용으로 이어질 수 있음
- 긴 문맥, 복잡한 추론, 과도한 출력 생성이 흔한 공격 수단임
- 초당 요청 수만 보는 전통적 레이트 제한으로는 놓치기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 네트워크 DDoS | 모델 DoS |
|:---|:---|:---|
| 주된 공격 자원 | 대량 패킷과 연결 수 | 계산이 무거운 프롬프트와 긴 출력 |
| 타격 지점 | 회선, 네트워크 장비, 웹 서버 | GPU, 메모리, 토큰 예산, 추론 대기열 |
| 흔한 징후 | 초당 요청 수 급증 | 요청 수는 적어도 지연과 단가가 급증 |
| 방어 초점 | 대역폭 흡수와 연결 차단 | 입력 길이와 출력 길이와 비용 한도 제어 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| API 게이트웨이 | 사용자 요청을 받아 기본 인증과 호출 제한을 수행함 |
| 입력 정책 | 입력 길이, 첨부 크기, 허용 도구 범위를 먼저 제한함 |
| 추론 스케줄러 | GPU 작업 큐를 나누고 동시 실행 수를 조절함 |
| 모델 실행기 | 실제로 토큰을 생성하며 자원을 가장 많이 씀 |
| 비용·지연 모니터링 | 요청당 토큰 수와 지연과 실패율을 감시함 |

```text
사용자 요청 -> 입력 정책 -> 추론 스케줄러 -> 모델 실행기 -> 응답
                                   |
                                   +-> 비용·지연 모니터링
```

## Ⅴ. 원리 및 절차 흐름도

```text
고비용 입력 전송 -> 추론 큐 점유 -> GPU와 메모리 소모 증가 -> 지연과 비용 급등 -> 정상 요청 처리 저하
```

1. **고비용 입력 전송**: 공격자가 긴 문서나 복잡한 요청을 보냄
2. **추론 큐 점유**: 요청 하나가 오래 실행되며 슬롯을 붙잡음
3. **자원 소모 증가**: GPU와 메모리와 출력 토큰 사용량이 커짐
4. **지연과 비용 급등**: 응답 시간이 늘고 자동 확장과 과금이 뒤따름
5. **정상 요청 저하**: 다른 사용자의 요청이 밀리거나 실패함

## Ⅵ. 실무 적용 및 유의점

1. 공개 LLM API는 입력 길이, 출력 길이, 사용자별 동시 실행 수를 함께 묶고 95백분위 응답 지연과 요청당 토큰 비용으로 점검함
2. 긴 문서 요약과 코드 분석 서비스는 전처리로 입력을 줄이고 비용 한도 초과 요청은 조기 종료하며 타임아웃 비율로 확인함

## Ⅶ. 결론

- 모델 DoS는 적은 요청으로도 큰 계산 비용을 일으키는 공격이므로 요청 수보다 요청 무게를 통제해야 함
