## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: 엄청나게 복잡한 질문이나 텍스트를 AI(챗봇)에게 고의로 던져서, **AI가 대답을 만들기 위해 서버의 GPU(그래픽 카드)와 메모리를 미친 듯이 소모하다가 결국 서버 자체가 터져버리게(다운되게) 만드는 AI 전용 서비스 마비 공격**입니다.
- **필요성**: 기존의 디도스(DDoS) 공격은 좀비 PC 1만 대를 동원해 웹사이트에 접속 버튼을 100만 번 눌러서 서버를 다운시켰습니다(엄청난 자본 필요). 그런데 AI 챗봇은 말 한마디 대답할 때마다 일반 웹페이지 접속의 1,000배가 넘는 컴퓨팅 연산(수학 계산)을 합니다. 해커는 무릎을 쳤습니다. "좀비 PC 1만 대? 필요 없어. 내 노트북 한 대로 챗봇한테 **'제일 계산하기 끔찍하게 어려운 질문 딱 10개'** 만 던지면 챗봇 서버 터지겠는데?" 
- **핵심 직관**: **"수학 천재에게 무한대 파이(π) 소수점 계산 시키기"**. 
  - 과거 (전통적 DoS): 식당(서버)에 건달(좀비 PC) 1만 명을 한꺼번에 보내서 문을 꽉 막아 다른 손님이 못 들어오게 함. (물량 공세).
  - **Model DoS**: 식당에 해커 혼자 들어갑니다. 그리고 천재 주방장(AI GPU)에게 세상에서 제일 요리하기 어려운 "10만 겹 페이스트리 미로 케이크(최악의 복잡도 프롬프트)"를 주문합니다. 주방장이 그 케이크 하나를 만드느라 주방을 100% 점유하고 밤을 새우며 뻗어버립니다. 밖에서 기다리던 정상적인 손님들은 요리를 하나도 받지 못해 식당(서비스)이 마비됩니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 대형 언어 모델(LLM) 기반의 서비스(예: ChatGPT, Claude) 운영 비용 중 90% 이상이 추론(Inference), 즉 사용자의 질문에 답을 생성하는 GPU 클라우드 비용입니다. LLM은 본질적으로 입력된 단어 수가 많아지면 연산량이 기하급수적(제곱)으로 늘어나는 구조(Transformer Attention)를 지닙니다. 해커가 이 구조적 비대칭성(Asymmetry)을 파고들어 극저비용으로 막대한 타격을 주는 가성비 끝판왕 공격이 탄생했습니다.
- **가치**: "파산 유도 공격 (Denial of Wallet)". 서버가 다운되는 것을 넘어, 클라우드 자동 확장(Auto-scaling) 기능이 켜져 있을 경우, 폭발하는 GPU 연산량을 감당하기 위해 서버가 100대씩 켜지면서 **회사에 하룻밤 새 수천만 원의 클라우드 요금 폭탄**을 안겨 파산시키는 치명적인 비즈니스 위협으로 작용합니다.

## 3. 어떻게 작동하는가? (Mechanism)
AI의 머리를 터지게 만드는 '악성 프롬프트(Sponge Example)'의 비밀.

1. **복잡도 극대화 질문 (Sponge Examples / Energy-Latency Attack)**
   - 평범한 질문: "안녕, 오늘 날씨 어때?" (GPU 연산 0.1초 컷).
   - 해커의 질문: "내가 지금부터 영어 단어 10,000개를 줄게. 이 단어들의 모든 철자를 거꾸로 뒤집고, 짝수 번째 철자만 빼서 라틴어로 번역한 다음, 그 결과값을 다시 알파벳 순서대로 정렬해서 표로 그려봐. [여기에 무의미한 텍스트 5만 자 붙여넣기]"
   - 모델의 반응: LLM의 Attention 매커니즘은 문장이 길어질수록 계산량이 제곱($N^2$)으로 폭발합니다. 이 질문을 해석하려다 GPU 메모리(VRAM)가 100%를 치고 응답 지연(Latency)이 30초, 1분으로 늘어납니다.
2. **동시 다발성 자원 고갈 (Resource Exhaustion)**
   - 해커는 노트북 1대로 이런 악성 프롬프트 10~20개를 병렬로 챗봇 API에 발사합니다.
   - 단 20개의 질문만으로 수천만 원짜리 H100 GPU 서버 클러스터가 뻗어버립니다(OOM: Out Of Memory 크래시).
3. **가변 길이 오버플로우 (Infinite Generation)**
   - 해커가 "원주율(파이)을 끝없이 출력해" 또는 무한 루프에 빠지는 코드를 짜달라고 해서 챗봇이 출력을 멈추지 못하게(Max Token 도달까지) 만들어 리소스를 끝까지 쪽쪽 빨아먹습니다.

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례 (코드 분석 AI 폭파)**: 
  - 최근 코드 분석 AI를 타겟으로 한 논문 사례입니다. 해커가 AI에게 10만 줄짜리 코드를 던져주면서 "이 코드의 함수 종속성 트리를 다 그려줘"라고 명령합니다. 일반적인 정적 분석 도구는 1초 만에 끝나지만, 생성형 AI(LLM)는 이 10만 줄짜리 텍스트를 하나하나 문맥으로 파악(Attention)하려다 GPU가 펑 터져버렸습니다. 회사 시스템이 이 AI에 묶여있던 탓에 덩달아 뻗어버리는 장애가 발생했습니다.
- **주의점 및 흔한 오해**: 
  - "이거 그냥 WAF(웹 방화벽)에서 초당 클릭 수 제한(Rate Limiting) 걸면 막히는 거 아닙니까?" $\rightarrow$ **막을 수 없습니다.** 해커는 1초에 1만 번 클릭하는 게 아니라, 1분에 딱 1번 아주 점잖은 속도로 클릭합니다. 방화벽 입장에서는 너무나 평온한 정상 트래픽인데, 그 1개의 텍스트 덩어리가 AI 뱃속에 들어가면 핵폭탄으로 팽창(Amplification)하는 구조이기 때문입니다.

## 5. 핵심 비교 및 연결 개념 (Relation)

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 대형 언어 모델(LLM)이나 딥러닝 추론 파이프라인(Inference Pipeline)의 높은 연산 복잡도(Computational Complexity)를 악용하여, **극소수의 악의적으로 설계된 입력값(Sponge Examples, 고도화된 프롬프트)만으로 GPU 메모리, CPU 싸이클, 전력 소비량을 고갈시켜 정상적인 모델 서비스 가용성(Availability)을 파괴하는 비대칭 자원 소모 공격.** (OWASP LLM Top 10의 주요 위협).
- **가치**: 기존 OSI 3~4계층(네트워크)이나 7계층(웹 서버)의 DDoS 방어 메커니즘을 100% 무력화시킴. 트래픽 볼륨이 극도로 낮아 레이트 리미트(Rate Limit)나 봇 탐지 솔루션을 우회하며, 클라우드 환경에서는 과도한 스케일 아웃(Scale-out)을 유발해 막대한 금전적 타격을 입히는 **경제적 서비스 거부(E-DoS, Denial of Wallet)** 공격으로 직결되는 클라우드 네이티브 시대의 핵심 리스크.
- **판단 포인트**: IT 인프라 아키텍트는 트랜스포머(Transformer) 구조의 태생적 아킬레스건을 이해해야 합니다. LLM의 Self-Attention 메커니즘은 입력 시퀀스 길이 $N$에 대해 $O(N^2)$의 시간적/공간적 복잡도를 가집니다. 해커가 컨텍스트 윈도우(Context Window)를 꽉 채우는 쓰레기 텍스트(Junk Data)를 던지면, 백엔드의 VRAM(GPU 메모리) 할당량은 기하급수적으로 폭발하여 즉각적인 OOM(Out Of Memory) 패닉을 유발합니다.

### Ⅱ. 모델 DoS (Model Denial of Service)의 핵심 공격 벡터
해커가 GPU를 질식시키는 3가지 차원의 쿼리 증폭 전략.
1. **스폰지 예제 공격 (Sponge Example Attack)**
   - NLP 모델, 기계 번역기 등을 타겟팅. 입력은 평범해 보이지만 모델이 번역/분석하는 과정에서 내부 활성화 텐서(Activation Tensor)나 연산 루프가 비정상적으로 길어지도록 유도하는 에너지(Energy) 극대화 입력값.
2. **컨텍스트 오버플로우 및 연산 복잡도 공격**
   - RAG(검색 증강) 기반 챗봇에게 수백 페이지의 난해한 논문 PDF나 정규표현식으로 꼬인 텍스트 수만 자를 던져주며, **"이 텍스트의 구조를 전부 요약하고 문법적 오류를 찾아라"** 라고 지시. LLM 파라미터가 텍스트 전체의 연관성을 계산($N^2$)하느라 응답 대기 시간(Latency)이 타임아웃(Timeout) 한계치까지 치솟음.
3. **무한 생성 유도 (Max Token Exhaustion)**
   - LLM이 답변 생성을 멈추지 못하게 하여 아웃풋 토큰 제한(Output Token Limit) 끝까지 비용을 소진하게 만듦. (예: "원주율 파이를 네가 출력할 수 있는 최대 글자 수까지 적어").

### Ⅲ. 파급 효과 (Impact): 가용성 상실과 E-DoS
- **다른 테넌트의 침해 (Noisy Neighbor)**: 동일 GPU 클러스터를 쪼개서 쓰는(Multi-tenancy) 환경에서 특정 파드가 VRAM을 독식해 버리면, 같은 노드에 있는 정상적인 다른 회사의 챗봇 모델 컨테이너들까지 연쇄적으로 응답 불가 상태(OOM Killed)에 빠짐.
- **클라우드 요금 폭탄 (Denial of Wallet)**: 쿠버네티스의 HPA(Horizontal Pod Autoscaler)가 응답 지연을 감지하고 파드를 늘리면 $\rightarrow$ 해커가 악성 쿼리 조금 더 발사 $\rightarrow$ GPU 인스턴스 10대가 100대로 무한 복제 스케일링 $\rightarrow$ CISO는 다음 달 수억 원의 AWS 청구서를 받게 됨.

### Ⅳ. 아키텍처적 방어 및 완화(Mitigation) 전략
기존 방화벽이 아닌 MLOps 파이프라인 단의 자원 할당 제어가 필수적임.
1. **엄격한 하드 리밋(Hard Limit)과 자원 할당량(Quota) 강제**
   - 사용자 프롬프트 창에 입력 가능한 글자 수(Input Length 제한)를 보수적으로 설정(예: 최대 2,000자).
   - LLM 파라미터 내 설정: `max_tokens`(생성 최대 글자 수)를 엄격히 고정.
   - K8s 설정: 파드별 최대 GPU/메모리 상한선(cgroup Limit)을 엄격히 부여하여 노드 전체의 붕괴 방어.
2. **시맨틱/의미론적 속도 제한 (Semantic Rate Limiting)**
   - 초당 몇 번 접속했느냐(IP 기반)가 아니라, **"이 사용자가 최근 1시간 동안 얼마나 길고 복잡한 연산(Token 단위)을 요청했는가?"** 에 기반하여 쿼리량을 차단하는 토큰 기반 과금/차단 시스템 도입.
3. **입력 복잡도 전처리 검사 (Input Complexity Profiler)**
   - 헤비한 본 모델(GPT-4급)에 쿼리를 던지기 전, 극도로 가벼운 전처리 필터(Input Parser)를 둬서 "이 입력이 불필요한 반복 텍스트나 폭탄 코드를 담고 있는지" 빠르게 스캔 후 비정상 포맷이면 거절(Drop) 처리.

### Ⅴ. 결론 및 실무적 판단 포인트
- B2C AI 서비스를 구축하는 아키텍트는 "클라우드가 알아서 스케일 아웃(Scale-out) 해주니까 트래픽이 몰려도 장애는 안 나겠지"라는 아마추어적 낙관론을 버려야 합니다. Model DoS는 스케일 아웃을 유도하여 회사의 재정을 말려 죽이는(Wallet Exhaustion) 영악한 킬 체인입니다. 반드시 API 게이트웨이와 모델 서빙 계층 사이에 **User/IP 별 Token 할당량(Quota) 추적 DB(Redis 등)** 를 연동하여, 비정상적 연산 증폭 시도를 실시간 버블링(차단)하는 백엔드 아키텍처가 선결되어야 합니다.

### 💡 문제 유형별 목차 전환 포인트
- **[대형 언어 모델(LLM) 환경의 가용성(Availability) 위협 및 신종 서비스 거부 공격]**: Ⅰ과 Ⅱ번(스폰지 예제 및 Transformer의 $N^2$ 복잡도 약점)을 핵심으로 다루며, 기존의 네트워크 디도스와 본질적으로 다른 극저비용/고효율 비대칭 공격의 무서움 논증.
- **[클라우드 네이티브 기반 AI 인프라의 경제적 위협(E-DoS) 및 자원 방어 전략]**: Ⅲ번(Denial of Wallet 파산 시나리오)의 치명성을 짚고, Ⅳ번의 방어 기법인 '토큰 기반 시맨틱 제한(Semantic Rate Limiting)'과 '하드 리밋 제어'를 통해 클라우드 스케일링의 양날의 검을 통제하는 방안 제시.
