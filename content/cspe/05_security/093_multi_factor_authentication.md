# 📖 【암기용】 개념 완전 이해

> 목적: MFA를 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 서로 다른 인증 요소 둘 이상을 조합해 세션 발급 전 추가 검증을 수행하는 인증 방식
- **왜 필요한가**: 비밀번호는 유출 DB, 피싱 페이지, 키로거, 재사용 공격에 노출된다. MFA는 비밀번호가 유출되어도 소유 장치나 생체 검증을 추가로 요구한다.
- **핵심 직관**: 문이 두 개인 것이 아니라 서로 다른 종류의 자물쇠를 거는 것이다.

## 깊이 이해
- **배경·문제의식**: 원격근무, SaaS, 관리자 콘솔 확산으로 계정 탈취가 주요 침입 경로가 되었다. 그러나 모든 MFA가 같은 수준은 아니다. SMS OTP는 SIM swap, Push MFA는 fatigue 공격, TOTP는 피싱 프록시에 취약할 수 있다.
- **작동 원리**: IdP는 1차 인증 후 사용자, 단말, 위치, 행위 위험도를 평가한다. 정책에 따라 TOTP, Push number matching, FIDO2, 생체 user verification을 요구하고 성공하면 세션 신뢰 수준과 만료 시간을 부여한다.
- **비유**: 은행 창구에서 신분증만 보지 않고, 고액 이체에는 보안카드나 실물 인증 장치를 추가 요구하는 절차와 같다.
- **구체 예시**: 관리자 콘솔은 password+FIDO2를 기본 적용하고, 해외 IP 또는 신규 단말 접속은 step-up을 강제한다. Push는 2자리 숫자 확인과 요청 위치 표시를 포함한다.
- **흔한 오해·주의점**: Push 승인 버튼만 추가하면 충분하지 않다. 반복 Push로 사용자를 지치게 하는 push fatigue 공격을 막기 위해 number matching, 요청 횟수 제한, 신고 버튼이 필요하다.

## 연결 개념
- Authentication Factors - MFA의 요소 독립성 기준
- FIDO2/WebAuthn - 피싱 저항 MFA 구현
- Risk-Based Authentication - 위험도 기반 step-up

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: MFA 답안은 OTP 나열이 아니라 요소 독립성, step-up 기준, push fatigue 대응, 실패 로그를 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MFA는 knowledge, possession, inherence 중 독립된 요소 둘 이상으로 계정 접근을 검증하는 인증 통제임
> 2. **가치**: 비밀번호 유출 후에도 소유 장치, FIDO2 키, 생체 user verification을 추가 요구해 계정 탈취 경로를 차단함
> 3. **판단 포인트**: 고위험 계정은 FIDO2, 일반 계정은 TOTP/Push number matching, 고위험 행위는 risk-based step-up으로 설계해야 함

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MFA 본질 이해 확인 | 요소 독립성, 2FA와 MFA 차이, 인증 강도 | 비밀번호+보안질문을 MFA로 서술 |
| 공격 대응 설계 확인 | phishing proxy, push fatigue, SIM swap | Push 승인만 방안으로 제시 |
| 운영 기준 확인 | step-up 조건, 재인증 주기, 실패 로그 | 등록률과 우회 계정 관리 누락 |

> 요약: 이 문제는 MFA 수단 명칭보다 업무 위험도에 맞는 요소 선택과 우회 방지 운영을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 독립 인증 요소 조합
- 배경: 비밀번호 단독 인증은 유출 DB 대입, 피싱, 재사용 공격에서 동일 비밀값 하나로 우회될 수 있다.
- 필요성: NIST SP 800-63B AAL2 이상 요구 시 OTP, FIDO2, 생체 잠금 해제 등 추가 요소로 침입 성공 조건을 늘려야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User -> IdP -> Primary Auth -> Risk Engine -> MFA Challenge -> Session
                  / Password
                  / TOTP, Push, FIDO2
                  / Device, Location, Behavior
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Primary Auth | 1차 인증 수행 | password, SSO, certificate |
| MFA Factor | 추가 요소 검증 | TOTP 30초, Push, FIDO2, biometric |
| Risk Engine | step-up 필요성 판단 | 신규 단말, 위치, IP, 행위 |
| Session Policy | 인증 강도별 세션 부여 | 관리자 세션 4시간, 재인증 |
| Audit Log | 성공·실패·우회 기록 | SIEM, UEBA, helpdesk 연계 |

> 요약: MFA는 IdP, 추가 요소, 위험 엔진, 세션 정책, 감사로그가 결합된 인증 운영 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그인 -> 1차 인증 -> 위험도 산정 -> MFA 방식 선택
-> challenge 검증 -> 세션 발급/거부 -> 실패·우회 로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | ID/PW 또는 SSO 인증 | breached password, 실패 횟수 제한 |
| 2 | 위험도 산정 | 신규 단말, impossible travel, Tor/VPN |
| 3 | 추가 인증 요구 | TOTP, Push number matching, FIDO2 |
| 4 | 세션 발급 | authn strength, TTL, step-up claim |
| 5 | 실패 대응 | 401 로그, 계정 잠금, 사용자 신고 |

> 요약: MFA는 로그인 후 위험도를 판단하고, 업무 민감도에 따라 추가 인증과 세션 신뢰 수준을 결정한다.

## Ⅳ. 특징

| 구분 | 기존/약한 방식 | MFA 적용 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 요소 | password 단독 | knowledge+possession/inherence | 관리자 MFA 100% |
| Push | 단순 승인 | number matching, 위치 표시, 신고 버튼 | Push 5회 실패 시 잠금 |
| Step-up | 로그인 시 1회 | 결제·권한 변경·다운로드 재인증 | 고위험 행위 100% 재인증 |
| 피싱 저항성 | TOTP 코드 입력 | FIDO2 origin binding | 관리자 FIDO2 등록률 95% 이상 |

> 요약: MFA 품질은 수단 개수보다 피싱 저항성, step-up 적용률, 우회 계정 관리 수준으로 판단한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 일반 사용자 | password only | TOTP 또는 Push number matching | 비용과 사용성, 피싱 노출 |
| 관리자 | TOTP | FIDO2 보안키 2개 등록 | 콘솔, CI/CD, VPN 접근 |
| 고객 거래 | 매 로그인 MFA | 위험 기반 step-up | 결제, 개인정보, 기기 등록 |

> 요약: MFA는 모든 요청에 같은 수단을 붙이는 방식보다 계정 권한과 행위 위험도별로 선택해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Push fatigue | 반복 승인 요청 | number matching, 요청 제한, 신고 버튼 | 사용자당 Push 실패 횟수 |
| SIM swap | SMS 번호 탈취 | SMS 제외, TOTP/FIDO2 전환 | 전화번호 변경 후 위험 이벤트 |
| 우회 계정 | 예외 정책 방치 | break-glass 계정 2개 이하, 금고 보관 | MFA 예외 계정 수 |

> 요약: MFA 운영 위험은 Push 피로, SMS 탈취, 예외 계정이며 예외 정책 축소와 이벤트 로그 감사로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 적용률 | 관리자 MFA 100%, 일반 사용자 95% 이상 | IdP enrollment report |
| 인증 품질 | 고위험 계정 FIDO2 95% 이상 | authn method inventory |
| 탐지·대응 | Push 실패 5회 이상 경보 | SIEM, UEBA, helpdesk ticket |

> 요약: MFA 성공 기준은 적용률, 고위험 계정의 FIDO2 비율, 실패 이벤트 탐지로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 기본 정책: 관리자·개발자·재무 계정은 FIDO2 보안키 2개 등록, 일반 사용자는 TOTP 또는 Push number matching 적용
2. Risk-based step-up: 신규 단말, 해외 IP, 결제, 권한 변경, 개인정보 다운로드 시 재인증과 세션 TTL 4시간 이하 적용
3. 운영 통제: MFA 예외 계정 2개 이하 관리, Push 실패 5회 경보, 401/MFA failure 로그를 SIEM과 helpdesk에 연계

**결론 (2줄):**
- 기술사 판단: MFA는 독립 요소 조합과 위험 기반 step-up을 함께 설계해야 하며, 관리자 계정은 FIDO2를 우선 선택해야 함
- 향후 방향: MFA는 OTP 중심에서 FIDO2, passkey, continuous risk signal 기반 재인증으로 이동함
