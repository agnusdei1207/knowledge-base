# 📖 【암기용】 개념 완전 이해

> 목적: NIST CSF 2.0의 Govern 기능 추가 의미를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, CSF 1.1과 2.0의 차이를 직관으로 설명한다.

## 한눈에
- **개요**: NIST CSF 2.0은 Govern을 추가해 사이버 위험을 전사 위험관리와 연결한 프레임워크이다.
- **왜 필요한가**: 보안팀 중심의 Identify-Protect-Detect-Respond-Recover만으로는 예산, 책임, 공급망, 위험 허용도를 경영 의사결정에 반영하기 어렵다.
- **핵심 직관**: Govern은 다른 5개 기능을 움직이는 운영 규칙과 책임 체계이며, 보안 통제를 "누가 어떤 위험 기준으로 승인하는가"로 바꾼다.

## 깊이 이해
- **배경·문제의식**: CSF 1.1은 5개 기능으로 보안 활동을 설명했지만, 공급망과 클라우드 의존도가 높아지면서 조직 맥락, 정책, 책임, 감독을 별도 축으로 올릴 필요가 생겼다. NIST CSF 2.0은 2024년 공개되며 모든 규모 조직을 대상으로 Govern을 중심에 둠.
- **작동 원리**: Govern은 GV.OC, GV.RM, GV.RR, GV.PO, GV.OV, GV.SC로 구성된다. 조직 맥락과 위험전략을 정하고, 역할·책임·정책·감독·공급망 위험관리를 설정한 뒤 나머지 5개 기능의 우선순위를 결정한다.
- **비유**: 병원 응급실에서 치료 행위가 Protect·Detect·Respond라면, Govern은 환자 분류 기준, 책임 의사, 예산, 법적 동의, 협력 병원 계약을 정하는 병원 운영 규정이다.
- **구체 예시**: 랜섬웨어 대응에서 Govern은 이사회 보고 주기 월 1회, 백업 RPO 15분, 핵심 서비스 RTO 4시간, 공급업체 보안등급 B 이상, 사고 보고 책임자 CISO를 지정한다.
- **흔한 오해·주의점**: Govern은 문서 작성 부서가 아니다. 정책이 있어도 위험 허용도, 책임자, KPI, 공급망 통제가 운영 지표와 연결되지 않으면 CSF 2.0 답안에서 감점된다.

## 연결 개념
- NIST CSF: 2.0의 상위 구조이며 Govern, Identify, Protect, Detect, Respond, Recover 6개 기능으로 구성됨
- NIST SP 800-53: 정책·절차, 위험관리, 공급망 통제의 세부 통제 카탈로그로 매핑 가능함
- ISO/IEC 27001: ISMS 인증 통제와 CSF Profile 간 교차 매핑 가능함

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CSF 2.0 답안은 Govern 추가 사실보다 GV 6개 범주가 Profile, Tier, 공급망, 경영 보고 지표를 어떻게 바꾸는지 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NIST CSF 2.0은 Govern을 중심 기능으로 추가해 사이버 위험관리 전략, 기대사항, 정책을 수립·전파·감독하는 프레임워크이다.
> 2. **가치**: Govern은 Current/Target Profile의 우선순위와 예산 배분을 조직 임무, 이해관계자 요구, 위험 허용도에 맞춘다.
> 3. **판단 포인트**: GV.OC·GV.RM·GV.RR·GV.PO·GV.OV·GV.SC를 빠뜨리면 CSF 1.1 답안에 머무른다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CSF 2.0 개정 차이 확인 | Govern 추가, 6개 기능, GV 6개 범주 | 5개 기능만 쓰거나 Govern을 Identify 하위로 설명 |
| 경영 위험관리 연계 판단 | 위험 허용도, 책임·권한, 정책, 감독, 공급망 | 표준명 나열 후 KPI·책임체계 누락 |
| 도입 방안 설계 역량 확인 | Current/Target Profile, Tier, 로드맵, 이사회 보고 | 인증 취득 절차처럼 작성 |

> 요약: 이 문제는 Govern을 통해 보안 통제를 경영 책임, 위험 허용도, 공급망 감독으로 전환하는 능력을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: NIST CSF 2.0 사이버 위험관리 체계
- 배경: CSF 1.1의 5개 기능은 실행 활동 중심이라 경영진 책임·공급망 위험·잔여위험 승인 기준을 별도 축으로 드러내기 어려웠다.
- 필요성: Govern 기능으로 정책, 책임자, 위험수용, 공급업체 요구사항을 NIST CSF 2.0 프로파일 기준으로 관리한다.

---

## Ⅱ. 구조 및 구성요소

```text
Mission / Stakeholder / Law -> GOVERN
  -> GV.OC / GV.RM / GV.RR / GV.PO / GV.OV / GV.SC
  -> Identify / Protect / Detect / Respond / Recover
  -> Current Profile / Target Profile / Tier / Roadmap
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| GV.OC | 조직 맥락, 임무, 이해관계자 요구 식별 | 규제·계약·서비스 의존성 반영 |
| GV.RM | 위험관리 전략, 위험 허용도, 우선순위 수립 | ERM·예산계획과 연결 |
| GV.RR | 역할, 책임, 권한 배정 | CISO, DPO, 서비스 오너 RACI |
| GV.PO/GV.OV | 정책 수립과 감독 수행 | 정책 승인, KPI 보고, 감사 |
| GV.SC | 공급망 사이버 위험관리 | 계약 보안요건, 제3자 평가 |

> 요약: Govern은 조직 맥락, 위험전략, 책임, 정책, 감독, 공급망을 묶어 다른 5개 기능의 실행 기준을 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
조직 맥락 정의 -> 위험 허용도 수립 -> 책임·정책 지정
-> 공급망 요구 반영 -> Current Profile 평가
-> Target Profile 설정 -> 갭 로드맵 -> 감독·개선 보고
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 임무, 법규, 계약, 핵심 서비스 범위 정의 | 서비스 등급, 규제 목록, 이해관계자 |
| 2 | 위험 허용도와 보안 목표 수립 | RTO 4시간, RPO 15분, MTTD 30분 |
| 3 | 역할·정책·공급망 요건 배정 | RACI, 정책 승인일, 계약 보안조항 |
| 4 | Profile 갭과 Tier 평가 | 고위험 갭 수, Tier 목표 |
| 5 | 로드맵 실행과 감독 보고 | 분기 완료율, 잔여위험 승인율 |

> 요약: CSF 2.0 적용은 Govern 기준을 먼저 세운 뒤 Profile 갭을 지표와 책임자로 줄이는 흐름이다.

## Ⅳ. 특징

| 구분 | CSF 1.1 | CSF 2.0 Govern | 수치·판단 기준 |
|:---|:---|:---|:---|
| 기능 구조 | ID·PR·DE·RS·RC 5개 | GV 포함 6개 기능 | Govern 범주 6개 반영 여부 |
| 책임 체계 | 보안팀 실행 중심 | 이사회·경영진·CISO·업무오너 책임 | RACI 100% 지정 |
| 공급망 | Identify 중심 일부 반영 | GV.SC로 전사 위험에 포함 | 주요 협력사 평가 연 1회 |
| 성과 관리 | 통제 이행률 중심 | 위험 허용도와 KPI/KRI 중심 | MTTD, MTTR, RTO/RPO |

> 요약: CSF 2.0 Govern은 보안 활동을 통제 목록에서 책임·위험 허용도·공급망 감독 지표로 전환한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| ISO 27001 | 인증 심사와 통제 적합성 | CSF 2.0 Govern 기반 로드맵 | 인증 목적은 ISO, 전사 위험 보고는 CSF |
| NIST SP 800-53 | 세부 통제 카탈로그 | 상위 경영·위험 구조 | 통제 구현은 800-53, 우선순위는 CSF |
| ERM | 재무·운영 위험 중심 | 사이버 위험을 ERM에 편입 | 이사회 위험보고 체계 존재 여부 |

> 요약: Govern은 ISO·800-53 통제를 대체하지 않고 전사 위험관리와 연결하는 상위 판단 틀로 사용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문서화 편중 | 정책만 만들고 Profile 갭 미측정 | Target Profile과 분기 로드맵 연결 | 고위험 갭 분기 20% 감소 |
| 책임 공백 | 업무오너와 보안오너 구분 없음 | RACI와 잔여위험 승인권자 지정 | 책임자 미지정 과제 0건 |
| 공급망 누락 | 협력사 보안요건 계약 미반영 | GV.SC 기반 보안조항·평가 도입 | 주요 협력사 평가율 100% |

> 요약: Govern 실패는 정책 부재보다 책임·지표·공급망 요구가 운영 프로세스에 연결되지 않을 때 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| Govern 커버리지 | GV 6개 범주 100% 평가 | CSF 2.0 평가표, GRC 대시보드 |
| 경영 보고 | 분기 1회 이상 위험·예산 보고 | 이사회·리스크위원회 회의록 |
| 성과 지표 | MTTD 30분, MTTR 4시간, RTO 4시간 | SIEM, SOAR, DR Drill |

> 요약: CSF 2.0 도입 성과는 GV 범주 커버리지, 경영 보고 주기, 탐지·대응·복구 지표로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. GV.OC~GV.SC 기준으로 조직 맥락, 위험 허용도, RACI, 정책, 공급망 요구를 30일 내 Current Profile에 반영함.
2. Target Profile을 서비스 등급별로 정의하고 핵심 서비스 RTO 4시간, RPO 15분, MTTD 30분을 KPI로 지정함.
3. 분기별 이사회 보고에 고위험 갭, 잔여위험 승인, 협력사 평가율, 사고대응 훈련 결과를 포함함.

**결론 (2줄):**
- 기술사 판단: 보안 실행 개선만 묻는 경우 기존 CSF 기능을 쓰고, 경영 책임·공급망·예산 우선순위가 보이면 CSF 2.0 Govern을 중심에 둔다.
- 향후 방향: CSF 2.0 Govern은 AI 위험, 클라우드 공급망, 개인정보 거버넌스와 같은 전사 위험 지표로 확장된다.
