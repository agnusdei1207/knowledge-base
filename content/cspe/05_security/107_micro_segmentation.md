## 미리 알고가기

- 세그멘테이션은 네트워크를 구역으로 나누는 것이고, 마이크로 세그멘테이션은 그 단위를 서버나 워크로드 수준까지 더 잘게 나누는 방식임
- 목적은 외부 침입 차단보다 내부에서 이미 들어온 공격의 측면 이동을 어렵게 만드는 데 있음
- 네트워크 장비만이 아니라 호스트 방화벽, 서비스 메시, eBPF 같은 기술도 집행 수단이 될 수 있음

## Ⅰ. 개요

- **정의/개념**: 마이크로 세그멘테이션은 애플리케이션, 서버, 컨테이너, 서비스 같은 워크로드 단위로 통신 허용 범위를 나눠 동서 트래픽을 제한하는 기법임
- **배경/필요성**: 데이터센터와 클라우드는 내부 통신이 많음. VLAN이나 경계 방화벽만으로는 횡적 이동을 막기 어려움

## Ⅱ. 특징

- 같은 내부망 안에서도 워크로드별 허용 통신을 구분함
- 기본 차단 후 필요한 흐름만 허용하는 화이트리스트 방식이 주로 쓰임
- 자산 라벨링과 통신 가시화가 선행되지 않으면 정책 설계가 어려워짐
- 에이전트 방식과 네트워크 방식에 따라 배포 난이도와 제어 정밀도가 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적 네트워크 분리 | 마이크로 세그멘테이션 |
|:---|:---|:---|
| 분리 단위 | 서브넷, VLAN, 구간 | 서버, 서비스, 컨테이너 |
| 강점 | 구조가 단순함 | 동서 트래픽 세밀 제어 가능 |
| 한계 | 같은 구역 내부 이동 통제가 약함 | 초기 가시화와 정책 설계 부담이 큼 |
| 적합 환경 | 단순 네트워크 구역화 | 클라우드, 가상화, 마이크로서비스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Visibility | 누가 누구와 통신하는지 흐름을 파악함 |
| Labels and Groups | 워크로드를 역할과 환경 기준으로 묶음 |
| Policy Engine | 허용 통신 규칙을 정의하고 배포함 |
| Enforcement | 호스트 방화벽, 에이전트, 서비스 메시가 정책을 집행함 |

```text
트래픽 가시화 -> 워크로드 라벨링 -> 허용 정책 정의 -> 집행 -> 위반 탐지와 조정
```

## Ⅴ. 원리 및 절차 흐름도

```text
통신 수집 -> 업무 흐름 분석 -> 라벨링 -> 기본 차단 정책 설정 -> 허용 목록 배포 -> 지속 튜닝
```

1. **통신 수집**: 내부 서비스 간 트래픽을 관찰함
2. **업무 흐름 분석**: 실제 필요한 연결만 추림
3. **라벨링**: 서비스 역할과 환경에 따라 그룹화함
4. **정책 배포**: 허용 연결만 남기고 차단 정책을 적용함
5. **지속 튜닝**: 누락과 과차단을 조정함

## Ⅵ. 실무 적용 및 유의점

1. 데이터센터·쿠버네티스는 내부 트래픽 가시화 후 기본 차단을 단계 적용하고 측면 이동 경로 감소와 정책 위반 탐지 정확도로 확인함
2. 레거시는 네트워크 방식과 호스트 방식을 섞고 커버리지 비율, 운영 복잡도, 예외 정책 누적으로 확인함

## Ⅶ. 결론

- 마이크로 세그멘테이션은 내부를 더 잘게 나누는 기술이 아니라 측면 이동을 허용 목록 중심으로 줄이는 제로 트러스트 구현 수단임
