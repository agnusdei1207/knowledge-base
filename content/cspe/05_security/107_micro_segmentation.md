## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 워크로드·애플리케이션 단위로 네트워크를 세분화하여 워크로드 간 통신을 정책으로 제어하는 제로 트러스트 네트워크 기법임 |
| **배경/필요성** | 기존 VLAN·방화벽 기반 세그멘테이션은 East-West 트래픽을 제어하지 못해 측면 이동(Lateral Movement)에 취약함 |
| **출제 의도** | 마이크로 세그멘테이션의 구현 방식과 측면 이동 억제 원리를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 워크로드  | --> | 정책엔진  | --> | 에이전트  |
| 라벨링   |     | (허용규칙)|     | (집행)   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 워크로드 라벨링 | 서버·컨테이너에 역할·환경·소유자 등 레이블을 부여하여 정책 대상을 정의함 | 사무실 구역 표지판 |
| 정책 엔진 | 레이블 기반 허용 규칙(화이트리스트)을 정의하고 배포함 | 구역 간 통행 허가서 |
| 호스트 에이전트 | 각 워크로드에 설치되어 정책을 로컬 방화벽 규칙으로 변환·집행함 | 각 구역의 출입문 경비 |

> 요약: 워크로드 라벨링 → 정책 정의 → 호스트 에이전트 집행으로 East-West 트래픽을 통제함.

## Ⅲ. 절차
```
+------------+     +------------+
| 트래픽     | --> | 워크로드   |
| 가시화     |     | 라벨부여   |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 모니터링   | <-- | 정책적용  |
| 위반탐지   |     | 트래픽제어 |
+------------+     +------------+
```

1. 트래픽 가시화: East-West 트래픽 흐름을 매핑하여 워크로드 간 통신 패턴을 파악함
2. 워크로드 라벨링: 앱·환경(Dev/Prod)·역할(웹/DB) 기준으로 모든 워크로드에 레이블을 부여함
3. 정책 적용: 레이블 기반 화이트리스트 정책을 정의하고, 에이전트가 호스트 방화벽으로 집행함
4. 모니터링·위반 탐지: 정책 위반 트래픽을 실시간 탐지·차단하고 보안 이벤트로 기록함

> 요약: 가시화 → 라벨링 → 정책 적용 → 모니터링으로 워크로드 단위 세분화를 구현함.

## Ⅳ. 문제점
- 초기 가시화 부담: 대규모 환경에서 모든 트래픽 흐름을 매핑하는 데 시간·노력이 소요됨
- 에이전트 관리: 수천 대 워크로드에 에이전트를 배포·업데이트하는 운영 부담이 큼
- 컨테이너 동적성: 컨테이너의 생성·소멸이 빈번하여 정적 정책이 부적합함

## Ⅴ. 개선방안
- (단기) AI 기반 자동 매핑: ML로 트래픽 패턴을 자동 분석하여 정책 추천을 제공함
- (중기) 서비스 메시 연동: Istio·Linkerd의 mTLS 정책과 마이크로 세그멘테이션을 통합함
- (장기) 에이전트리스 방식: eBPF 기반으로 에이전트 없이 커널 레벨에서 정책을 집행함

## Ⅵ. 전망
- eBPF 기반 Cilium 등 에이전트리스 마이크로 세그멘테이션이 확산되며, 제로 트러스트 East-West 방어의 핵심 기술로 자리잡을 전망임
