# 📖 【암기용】 개념 완전 이해

> 목적: 마이크로 세그멘테이션을 VLAN 분리와 구분해 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터센터·클라우드 내부 통신을 워크로드 단위 정책으로 분리하는 보안 통제
- **왜 필요한가**: 침해자는 최초 서버 장악 후 DB, 인증 서버, 관리망으로 이동한다. 방화벽이 외곽에만 있으면 동서 트래픽이 감시 밖에 놓인다.
- **핵심 직관**: 건물 입구 경비만 두는 대신 각 방 문마다 출입 명단을 붙이는 방식임

## 깊이 이해
- **배경·문제의식**: VLAN·서브넷 분리는 네트워크 주소 기준이다. 컨테이너, VM, 서버리스처럼 워크로드가 자주 이동하는 환경에서는 IP 기반 경계가 정책 의도를 잃기 쉽다.
- **작동 원리**: 워크로드 라벨, 서비스 계정, 프로세스, 포트, 태그를 수집해 허용 통신 맵을 만든다. 이후 정책 엔진이 허용 목록 외 east-west 트래픽을 차단하고 로그를 남긴다.
- **비유**: 병원에서 환자 병동, 약제실, 수술실을 카드 권한으로 나누는 것과 같다. 같은 건물 안이어도 역할이 다르면 문이 열리지 않는다.
- **구체 예시**: Web 서버는 App 서버 443/TCP만 허용, App 서버는 DB 5432/TCP만 허용, DB는 Web으로의 역방향 세션을 차단한다. 정책 위반 1건은 SIEM 경보로 전송한다.
- **흔한 오해·주의점**: 세그멘테이션은 네트워크 팀만의 VLAN 설계가 아니다. 앱 의존성 분석 없이 차단 모드로 전환하면 배치 작업, 백업, 모니터링 트래픽이 중단된다.

## 연결 개념
- Zero Trust — 내부망도 불신하고 최소 통신만 허용하는 원칙
- Kubernetes NetworkPolicy — 네임스페이스·파드 라벨 기반 마이크로 세그멘테이션 구현
- EDR/NDR — 워크로드 행위와 east-west 트래픽 관측 데이터 제공
- ZTNA — 사용자 접근은 ZTNA, 워크로드 간 통신은 세그멘테이션으로 분리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 마이크로 세그멘테이션은 네트워크 대역 분리가 아니라 워크로드 간 허용 통신을 명시해 lateral movement를 차단하는 통제임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 마이크로 세그멘테이션은 서버, VM, 컨테이너, 서비스 간 east-west 트래픽을 업무 단위 정책으로 제어하는 기술이다.
> 2. **가치**: 허용 목록 기반 통신, 라벨 정책, 로그 관측으로 침해 확산 경로를 포트·프로세스 단위까지 축소한다.
> 3. **판단 포인트**: 정책 전환은 의존성 맵 30일 수집, 모니터링 모드, 단계별 차단, 예외 만료일 관리 순서가 필요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 내부 이동 차단 원리 확인 | east-west 트래픽, allowlist, workload label, policy enforcement | VLAN·방화벽 분리만 설명 |
| 클라우드·컨테이너 적용 능력 확인 | Security Group, Kubernetes NetworkPolicy, Service Mesh mTLS | IP ACL만 제시 |
| 운영 리스크 판단 확인 | 의존성 분석, 차단 모드 전환, 예외 만료, 로그 검증 | 즉시 전면 차단 제안 |
> 요약: 이 문제는 내부망 침해 확산을 워크로드 정책으로 제한하는 구조와 운영 절차를 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 워크로드 단위 통신 제어
- 배경: 랜섬웨어와 계정 탈취 공격은 최초 침투 후 내부 서버 간 이동으로 피해 범위를 키우며 외곽 방화벽은 east-west 트래픽을 세밀하게 제어하지 못한다.
- 필요성: 앱 의존성 기반 허용 목록, L4/L7 정책, flow log 관측으로 NIST SP 800-207의 최소 권한 네트워크 접근을 구현해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Workload Inventory -> Traffic Discovery -> Policy Engine -> Enforcement Point
                                     +-> SIEM/NDR Logs
                                     +-> Exception Workflow
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Inventory | VM, 서버, 컨테이너, 라벨, 소유자 식별 | CMDB·CSP 태그 정합성 필요 |
| Traffic Discovery | 정상 통신 포트·프로세스·방향 수집 | 최소 30일 관측 권장 |
| Policy Engine | 허용 목록 정책 생성·배포 | 앱, 환경, 민감도별 정책 |
| Enforcement Point | 호스트 에이전트, SDN, 방화벽, CNI에서 차단 | 위치별 우회 경로 확인 |
| Logging | 허용·차단 이벤트 수집 | SIEM, NDR, SOAR 연계 |
> 요약: 세그멘테이션은 자산 식별, 통신 관측, 정책 엔진, enforcement, 로그가 결합되어 동작한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산 식별 -> 정상 통신 학습 -> 정책 초안 생성 -> 모니터링 모드
-> 예외 조정 -> 차단 모드 -> 위반 탐지/대응
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 앱과 워크로드 소유자 매핑 | CMDB 매핑률 95% 이상 |
| 2 | east-west 트래픽 30일 수집 | 배치·백업·모니터링 포함 |
| 3 | 허용 정책 생성 및 리뷰 | 업무 소유자 승인, 만료일 지정 |
| 4 | 모니터링 모드로 오탐 확인 | 차단 후보 오탐률 3% 이하 |
| 5 | 차단 모드 적용 및 경보 연계 | 위반 이벤트 SIEM 전송 100% |
> 요약: 차단보다 먼저 관측과 정책 검증을 수행해야 업무 중단 없이 내부 이동 경로를 줄일 수 있다.

## Ⅳ. 특징

| 구분 | VLAN/서브넷 분리 | 마이크로 세그멘테이션 | 정량·기술 포인트 |
|:---|:---|:---|:---|
| 정책 기준 | IP 대역, L3 경계 | 워크로드 라벨, 앱 역할, 프로세스 | 라벨 적용률 95% 이상 |
| 제어 범위 | 남북 트래픽 중심 | 동서 트래픽 중심 | east-west 로그 100% 수집 |
| 변경 대응 | IP 변경 시 ACL 수정 | 태그·라벨 기반 정책 유지 | IaC 정책 배포 |
| 보안 효과 | 서브넷 간 이동 제한 | 서버 간 불필요 통신 차단 | 미허용 포트 0개 목표 |
> 요약: 마이크로 세그멘테이션은 주소 기반 경계를 업무 역할 기반 정책으로 바꿔 내부 이동 경로를 축소한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 마이크로 세그멘테이션 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 중앙 방화벽, VLAN ACL | 호스트·SDN·CNI enforcement | VM·컨테이너 혼재, 앱 수 50개 이상 |
| 비용/성능 | 방화벽 경유로 hairpin 발생 | 로컬 정책 적용 | p95 앱 지연 증가 5ms 이하 |
| 운영/위험 | 네트워크팀 중심 변경 | 앱 소유자 승인 워크플로우 | 변경 티켓 SLA 3영업일 |
> 요약: 워크로드 이동이 잦고 동서 트래픽이 많은 환경에서는 라벨 기반 세그멘테이션을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 중단 | 의존성 누락 후 차단 적용 | 30일 학습, 모니터링 모드, 카나리 적용 | 차단 오탐률 3% 이하 |
| 정책 노후화 | 앱 변경 후 라벨·포트 미갱신 | IaC, 정책 리뷰 월 1회 | 만료 예외 0건 |
| 우회 통신 | 관리망·백업망 예외 과다 | 관리 포트 PAM 연계, 백업망 정책 분리 | 비인가 east-west 0건 |
> 요약: 운영 리스크는 학습 기간, 예외 만료, 변경 자동화로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 커버리지 | Tier-1 앱 100%, 전체 워크로드 90% 이상 | CMDB, CSP 태그, 에이전트 현황 |
| 통신 통제 | 미허용 포트 0개, 차단 이벤트 MTTA 10분 | NDR, SIEM, SOAR |
| 변경 품질 | 정책 변경 실패율 1% 이하 | Change log, 배포 파이프라인 |
> 요약: 세그멘테이션 성과는 커버리지, 미허용 포트, 탐지 시간, 변경 실패율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Discover: CMDB·flow log·EDR로 앱 의존성 30일 수집, Web/App/DB/Management Zone 라벨 정의
2. Enforce: 중요 시스템부터 monitor 모드 2주 후 deny 모드 전환, Kubernetes는 NetworkPolicy와 CNI 로그 적용
3. Operate: 정책을 GitOps로 관리하고 예외는 만료일 30일 이하, 차단 이벤트는 SIEM과 SOAR playbook으로 처리

**결론 (2줄):**
- 기술사 판단: 규제 대상 DB와 중요 업무 시스템은 마이크로 세그멘테이션을 우선 적용하고, 단순 사무망은 VLAN+NAC로 분리한다.
- 향후 방향: ZTNA, Service Mesh mTLS, CNAPP와 결합해 사용자 접근부터 워크로드 간 통신까지 단일 정책으로 수렴한다.
