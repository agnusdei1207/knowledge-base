## Ⅰ. 개요
- **정의**: 관리자·시스템 계정 등 특권 접근 권한의 발급·사용·감사를 통합 관리하는 보안 체계
- **배경/필요성**: 특권 계정 탈취가 대규모 침해의 주요 경로이며, 공유 계정 사용으로 책임 추적이 곤란함
- **비유**: 금고 열쇠를 개인에게 맡기지 않고, 사용 시마다 금고실 관리자가 꺼내주고 기록하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 특권 계정 관리 필요성과 구현 | 자격 증명 보관소·세션 기록·JIT 접근 | IAM(102)과의 범위 차이 혼동 주의 |

> 요약: PAM은 특권 계정의 자격 증명·세션·감사를 중앙에서 통제하는 보안 체계임

## Ⅱ. 구성요소
```text
[관리자] --> [PAM Gateway] --> [자격증명 보관소] --> [대상 시스템]
                 |                                      |
          세션 기록/감시                           명령 필터링
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Credential Vault | 특권 계정 비밀번호를 암호화 저장하고 자동 순환함 | 은행 금고 |
| Session Manager | 특권 세션을 중계하며 화면·명령을 실시간 기록함 | CCTV 녹화기 |
| JIT Provisioning | 요청 시점에 한시적 권한을 부여하고 만료 후 자동 회수함 | 임시 출입증 |
| Access Workflow | 승인 절차를 통해 특권 사용 요청을 검토·인가함 | 결재 시스템 |

> 요약: 자격 증명 보관·세션 기록·한시적 권한 부여가 PAM의 핵심 구성임

## Ⅲ. 절차
```text
권한 요청 --> 승인 워크플로 --> 자격증명 대출 --> 세션 기록/회수
```
- 1단계: 관리자가 대상 시스템 접근을 위해 PAM 포털에 권한을 요청함
- 2단계: 승인자가 요청 사유·범위를 검토하여 승인하면 JIT 권한이 활성화됨
- 3단계: Credential Vault에서 자격 증명을 자동 주입하고 세션을 개시함
- 4단계: 세션 종료 후 비밀번호를 자동 순환하고 감사 로그를 보관함

> 요약: 요청→승인→자격증명 대출→자동 회수의 흐름으로 특권 사용을 통제함

## Ⅳ. 문제점
- 우회 접근: SSH 키·API 토큰 등 PAM을 거치지 않는 비관리 자격 증명이 잔존함
- 운영 마찰: 긴급 상황에서 승인 워크플로가 대응 속도를 지연시킴
- 서비스 계정 관리 부재: 애플리케이션 내장 서비스 계정은 PAM 범위에서 누락되기 쉬움

> 요약: 비관리 자격 증명, 운영 마찰, 서비스 계정 사각지대가 과제임

## Ⅴ. 개선방안
1. 단기: SSH 키·API 토큰까지 Vault 관리 범위를 확장하여 우회 경로를 차단함
2. 중기: 긴급 접근용 Break-Glass 절차를 마련하여 사후 승인으로 대응 속도를 확보함
3. 장기: 서비스 계정 자동 발견·등록 기능을 도입하여 관리 사각지대를 해소함

> 요약: Vault 범위 확장 → Break-Glass → 서비스 계정 자동 등록으로 단계적 개선함

## Ⅵ. 전망
- 발전 방향: 클라우드 워크로드 특권 관리(CIEM)와 통합되어 멀티클라우드 환경으로 확장되는 추세임
- 기술사적 판단: 제로 트러스트의 최소 권한 원칙 구현에서 PAM이 핵심 수단으로 위상이 강화됨
- 기술사 제언: IAM-PAM-CIEM을 통합한 신원 보안 플랫폼 관점의 로드맵 수립이 필요함
