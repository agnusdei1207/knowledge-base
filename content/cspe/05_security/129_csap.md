# 📖 【암기용】 개념 완전 이해

> 목적: CSAP 보안 인증 등급제를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: CSAP는 국내 공공기관이 사용할 클라우드 서비스의 보안 통제 수준을 심사·인증하는 제도이다.
- **왜 필요한가**: 공공 데이터와 행정 서비스는 민간 클라우드를 쓰더라도 인증, 암호화, 망분리, 운영통제, 감사 기준을 충족해야 한다.
- **핵심 직관**: 공공 업무 중요도에 따라 클라우드 서비스의 보안 심사 강도를 상·중·하 등급으로 다르게 적용하는 제도임.

## 깊이 이해
- **배경·문제의식**: 공공 클라우드 전환은 민첩성을 제공하지만 데이터 주권, 운영자 접근, 장애 대응, 침해사고 책임 범위가 불명확하면 국가·공공 서비스 위험으로 이어진다.
- **작동 원리**: 클라우드 사업자는 관리적·물리적·기술적 보호조치와 운영 증적을 제출하고, 평가기관 심사와 보완 조치를 거쳐 인증을 받는다. 인증 후에도 주기적 사후관리와 변경 관리를 수행한다.
- **비유**: 건물 임대 전 소방·전기·출입통제 검사를 받고, 입주 후에도 정기 점검을 받는 구조와 같다.
- **구체 예시**: 공공 SaaS는 서비스 등급, 데이터 중요도, 인터넷 접근성, 개인정보 처리 여부에 따라 인증 등급과 망분리·암호화·접근통제 요구가 달라진다.
- **흔한 오해·주의점**: CSAP 인증은 모든 보안 책임을 CSP가 떠안는다는 뜻이 아니다. 기관은 계정·데이터·업무 설정과 로그 점검 책임을 공유한다.

## 연결 개념
- 클라우드 공동책임모델: CSP와 이용기관의 보안 책임 경계
- ISMS-P·ISO/IEC 27001: 관리체계와 통제 증적의 비교 기준
- CSPM·CASB: 인증 후 설정 편류와 SaaS 사용 위험 점검 도구

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 제도 목적, 등급 판단, 인증 후 운영통제를 연결해 작성한다.
> 핵심: CSAP는 단순 인증명이 아니라 공공 클라우드 도입의 위험등급별 통제 체계이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSAP는 공공기관 클라우드 이용을 위해 클라우드 서비스의 관리적·물리적·기술적 보호조치를 등급별로 검증하는 보안 인증 제도이다.
> 2. **가치**: 공공 데이터 중요도에 따라 인증 등급, 망분리, 접근통제, 로그·감사, 사고 대응 요건을 차등 적용한다.
> 3. **판단 포인트**: 인증 취득 여부보다 업무 등급, 데이터 위치, 운영자 접근, 공동책임 범위, 사후관리 체계를 확인해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공공 클라우드 보안 제도 이해 확인 | CSAP 목적, 등급제, 심사·사후관리 | 민간 보안 인증과 동일하게 설명 |
| 도입 판단 역량 확인 | 업무 중요도, 데이터 민감도, 망분리, 국내 운영 요건 | 인증만 있으면 공공 업무 전체 사용 가능하다고 단정 |
| 운영·감사 관점 확인 | 공동책임, 로그, 접근권한, 변경관리 | 기관 책임과 CSP 책임 경계 누락 |

> 요약: 이 문제는 공공 클라우드 이용 시 인증 등급과 업무 위험도를 맞추고, 인증 후 운영통제를 지속하는지를 평가한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 공공 클라우드 보안 인증
- 배경: 공공기관은 클라우드 전환 시 데이터 보호, 운영자 통제, 장애·침해 대응, 감사 증적 확보가 필요함.
- 필요성: KISA CSAP 등급제 기준으로 업무 중요도와 데이터 위험에 맞는 SaaS·IaaS·PaaS 사용 범위를 판단해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Public Workload -> Risk Classification -> CSAP Grade
  / Management Control
  / Physical Control
  / Technical Control
Assessment -> Remediation -> Certification -> Post Audit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 등급 분류 | 업무·데이터 위험에 따라 상·중·하 등급 적용 | 민감정보, 중요 서비스, 인터넷 노출 여부 고려 |
| 심사 통제 | 관리적·물리적·기술적 보호조치 검증 | 접근통제, 암호화, 로그, 사고 대응 포함 |
| 평가·인증 | 문서 심사, 현장 점검, 보완 조치 확인 | 인증 범위와 서비스명을 명확히 확인 |
| 사후관리 | 변경·장애·침해 대응과 정기 점검 | 인증 유지와 이용기관 감사 대응 |

> 요약: CSAP는 업무 위험 분류에서 시작해 등급별 통제 심사, 보완, 인증, 사후관리로 이어지는 공공 클라우드 보안 체계이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
서비스 도입 검토 -> 데이터·업무 중요도 분류
-> 인증 등급 확인 -> CSP 통제 증적 검토
-> 계약·공동책임 명시 -> 운영 로그·권한 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 대상 업무와 데이터 등급 식별 | 개인정보, 행정정보, 대국민 서비스 여부 |
| 2 | CSP의 CSAP 인증 범위 확인 | 인증 서비스명, 등급, 유효기간, 사후관리 |
| 3 | 공동책임과 운영통제 설계 | 계정, 암호화키, 로그 보존 1년 이상 |
| 4 | 도입 후 지속 점검 | 권한 리뷰 분기 1회, 침해 대응 훈련 연 1회 |

> 요약: CSAP 적용은 인증서 확인으로 끝나지 않고 업무 등급, 책임 경계, 운영 증적 점검까지 이어져야 한다.

## Ⅳ. 특징

| 구분 | 일반 민간 클라우드 인증 | CSAP 등급제 | 수치·기준 |
|:---|:---|:---|:---|
| 적용 대상 | 일반 기업 보안관리 | 공공기관 이용 클라우드 서비스 | 공공 업무·데이터 기준 |
| 통제 범위 | 조직·서비스 보안 통제 | 공공 요구 기반 등급별 통제 | 관리·물리·기술 통제영역 |
| 운영 요건 | 계약별 협의 | 인증 범위·사후관리·감사 대응 | 권한 리뷰 분기 1회 |
| 한계 | 공공 특수성 부족 | 인증 범위 밖 서비스 사용 제한 | 서비스별 인증 여부 확인 |

> 요약: CSAP는 공공 업무 사용 가능성을 판단하는 제도이므로 인증 범위, 등급, 사후관리 증적을 함께 확인해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 자체 전산센터 | CSAP 인증 클라우드 | 공공 업무 클라우드 전환, 감사 대응 필요 |
| 비용/성능 | 설비 직접 구축·운영 | 인증된 IaaS/PaaS/SaaS 사용 | 인증 범위와 데이터 위치 요구 충족 시 |
| 운영/위험 | 기관 단독 책임 | CSP·기관 공동책임 | 계정·데이터·로그 책임 경계 명시 |

> 요약: CSAP 클라우드는 자체 구축 대안과 비교해 인증 통제를 활용하되, 공동책임과 인증 범위가 선택 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 인증 범위 오인 | 서비스별 인증 여부 미확인 | 계약 전 인증서·서비스명·등급 대조 | 미인증 서비스 사용 0건 |
| 책임 공백 | CSP와 기관 통제 경계 불명확 | RACI, SLA, 침해 통보 시간 명시 | 권한 리뷰 분기 1회, 로그 보존율 100% |
| 변경관리 누락 | 클라우드 구성 편류 | CSPM, IaC 정책검사, 변경 승인 | critical misconfig 7일 내 조치 |

> 요약: CSAP 도입 위험은 인증 범위 오인과 책임 공백에서 발생하므로 계약·구성·감사 증적을 같은 기준으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 적합성 | 대상 서비스 CSAP 인증 범위 100% 일치 | KISA 인증 현황, 계약서 대조 |
| 운영 통제 | 관리자 MFA 100%, 권한 리뷰 분기 1회 | IAM 로그, 접근권한 보고서 |
| 감사 대응 | 로그 보존 1년 이상, 침해 훈련 연 1회 | SIEM, 훈련 결과보고서 |

> 요약: 도입 후 성공 여부는 인증서가 아니라 인증 범위 일치율, 권한 통제, 감사 증적 보존으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 업무 영향도·데이터 민감도·인터넷 노출 여부로 대상 시스템을 분류하고, 요구 등급과 CSP 인증 범위를 계약 전 대조함
2. 공동책임표(RACI)에 계정, 암호화키, 로그, 백업, 사고 통보 시간을 명시하고 관리자 MFA 100%를 계약 조건으로 둠
3. CSPM·SIEM·정기 권한 리뷰로 인증 후 구성 편류를 점검하고 critical 설정 오류는 7일 내 조치 SLA로 관리함

**결론 (2줄):**
- 기술사 판단: 공공 업무는 인증 등급과 데이터 위험이 일치할 때 도입하고, 인증 범위 밖 서비스는 별도 위험평가 후 제외 또는 보완해야 함
- 향후 방향: CSAP는 인증 취득 중심에서 운영 로그, 구성 편류, 공급망 증적을 지속 검증하는 체계로 발전해야 함
