## 미리 알고가기

- CSAP는 공공기관에 제공되는 클라우드 서비스의 보안 기준 준수 여부를 평가하는 국내 보안 인증 제도임
- 예비점검은 신청 전후에 준비 상태를 확인하는 단계이고 본점검은 현장평가와 취약점 점검을 포함하는 핵심 심사 단계임
- SaaS 등급은 제공 업무의 보호 요구 수준에 따라 적용 통제와 심사 깊이가 달라짐

## Ⅰ. 개요

- **정의/개념**: CSAP는 공공 부문 클라우드 서비스가 정해진 보안 기준을 충족하는지 평가·인증하는 제도이며 유형과 등급에 따라 심사 범위가 달라짐
- **배경/필요성**: 공공기관은 민간 클라우드를 쓰더라도 보안 수준을 일정하게 확인해야 함. 제도화된 평가 기준과 인증 절차가 필요함

## Ⅱ. 특징

- 클라우드 서비스 자체를 대상으로 보안 기준 준수 여부를 평가함
- 신청, 점검, 보완, 인증위원회, 사후평가까지 이어지는 공식 절차를 가짐
- 서비스 유형과 등급에 따라 심사 범위와 준비 자료가 달라짐
- 인증 취득 뒤에도 구조와 운영 변경을 관리하지 않으면 사후평가에서 문제가 다시 드러남

## Ⅲ. 종류 및 비교

| 판단 기준 | SaaS 간편등급 | SaaS 표준등급 |
|:---|:---|:---|
| 적용 대상 | 상대적으로 단순한 공공 SaaS 업무 | 보호 요구가 더 큰 공공 SaaS 업무 |
| 심사 깊이 | 필수 통제를 중심으로 간소화됨 | 더 넓은 통제 항목과 증적 준비가 필요함 |
| 도입 부담 | 준비 기간과 비용이 상대적으로 낮음 | 설계와 운영 증적을 더 촘촘히 맞춰야 함 |
| 적합 상황 | 범위가 좁고 표준화된 서비스 | 중요 정보와 운영 통제가 더 중요한 서비스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 신청 사업자 | 서비스 구조와 운영 증적을 준비해 인증을 신청함 |
| 평가 기준 | 서비스 유형과 등급에 맞는 보안 통제 항목을 제시함 |
| 평가 기관 | 예비점검, 본점검, 취약점 점검으로 적합 여부를 판단함 |
| 인증위원회 | 평가 결과와 보완 이행 상태를 검토해 인증 여부를 결정함 |
| 사후관리 | 인증 후에도 정기 점검과 변경관리로 상태를 유지함 |

```text
인증 신청 -> 예비점검 -> 본점검/취약점 점검 -> 보완 조치 -> 인증위원회 심의 -> 인증 및 사후관리
```

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 범위 확정 -> 증적 준비 -> 점검 수행 -> 부적합 보완 -> 심의 -> 인증 유지 관리
```

1. **서비스 범위 확정**: 어떤 서비스와 운영 구간을 인증 대상으로 볼지 정함
2. **증적 준비**: 아키텍처, 정책, 로그, 운영 절차를 준비함
3. **점검 수행**: 예비점검과 본점검과 취약점 점검을 진행함
4. **부적합 보완**: 부족한 통제와 문서를 수정하고 재확인받음
5. **인증 유지**: 변경 사항과 사후평가에 맞춰 상태를 유지함

## Ⅵ. 실무 적용 및 유의점

1. 공공 SaaS 사업자는 설계 단계부터 로그, 접근통제, 운영 절차 증적을 준비하고 주요 부적합 건수와 보완 완료 시간으로 확인함
2. 인증 후 서비스 구조와 외부 연계가 바뀌면 변경 영향 평가를 운영 절차에 넣고 미신고 변경 건수와 사후평가 지적 건수로 점검함

## Ⅶ. 결론

- CSAP는 공공 클라우드 도입을 위한 문서 심사가 아니라 서비스 설계와 운영 통제를 함께 검증하는 제도이므로 초기 설계와 변경관리까지 묶어 준비해야 함
