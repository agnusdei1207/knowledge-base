# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **양자내성암호(PQC)는 대규모 양자컴퓨터의 Shor 알고리즘으로도 깨지지 않는 수학 난제(격자 등)에 기반한 공개키 암호로, NIST가 FIPS 203(ML-KEM)·204(ML-DSA)·205(SLH-DSA)로 표준화함**. 개별 알고리즘 상세는 (016~018 참조), 전환 로드맵은 (019 참조).
- **왜 필요한가**: RSA·ECC는 소인수분해·이산로그 난제에 의존하는데 Shor 알고리즘이 이를 다항시간에 풀어버림. 지금 도청·저장한 암호문을 미래 양자컴퓨터로 복호하는 HNDL 공격이 현재부터 위협이므로 조기 전환이 필요함.
- **핵심 직관**: 기존 자물쇠는 "큰 수 인수분해"라는 어려운 문제로 잠갔는데, 양자컴퓨터라는 만능 열쇠가 그 문제만 쉽게 품. 그래서 양자컴퓨터도 못 푸는 다른 난제(격자 최단벡터 등)로 자물쇠 자체를 바꾸는 것임.

## 핵심 용어 정리 (내부에 등장하는 것들)

답안에 등장하는 위협·난제·표준·전략을 먼저 풀어 둠. 상위 핵심 키워드는 **양자내성(post-quantum)** 으로, 양자컴퓨터로도 실용 시간 내 못 푸는 난제 기반이라는 뜻임.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Shor 알고리즘 | 소인수분해·이산로그를 다항시간에 푸는 양자 알고리즘 | RSA·ECC 만능 열쇠 |
| Grover 알고리즘 | 탐색을 제곱근으로 가속(대칭키 강도 절반화) | AES-128을 64비트 수준으로 |
| CRQC | 암호학적으로 유의미한 양자컴퓨터 | 실제로 위협되는 규모의 양자컴퓨터 |
| HNDL | 수집 후 복호(Harvest Now, Decrypt Later) | 지금 훔쳐 미래에 열기 |
| 격자기반(Lattice) | 격자 최단·근접 벡터 난제 기반 암호 | 촘촘한 격자에서 길 찾기 |
| LWE/Module-LWE | 잡음 섞인 선형식 복원 난제 | 오차 낀 방정식 되풀기 |
| KEM | 키 캡슐화 메커니즘(공유키 합의) | 공개키로 잠근 비밀 상자 |
| ML-KEM / ML-DSA | 격자기반 표준 KEM / 서명(FIPS 203/204) | PQC 키교환 / PQC 서명 |
| SLH-DSA | 해시기반 서명 표준(FIPS 205) | 해시만으로 만든 서명 |
| 하이브리드 | 기존(ECDHE)+PQC를 동시 사용 | 이중 자물쇠 병용 |
| 암호 민첩성 | 알고리즘 교체가 쉬운 설계 | 부품처럼 갈아끼우기 |

## 깊이 이해
- **배경·문제의식**: 현재 인터넷 신뢰는 RSA·ECC(009·007)에 의존함. 그런데 충분히 큰 양자컴퓨터(CRQC)가 나오면 Shor 알고리즘이 이 둘을 무력화함. 대칭키·해시는 Grover로 강도가 절반이 될 뿐이라 키 길이를 2배(AES-256, SHA-384↑)로 늘리면 되지만, 공개키는 대체 알고리즘 자체가 필요함.
- **작동 원리(어떻게+왜)**: PQC는 양자컴퓨터도 이점이 없는 난제에 기반함. 대표는 격자기반으로, Module-LWE(잡음 낀 선형식 복원)의 어려움에 안전성을 둠. NIST는 2016년 공모를 시작해 2024년 8월 FIPS 203(ML-KEM, 키교환)·204(ML-DSA, 서명)·205(SLH-DSA, 해시기반 서명)를 확정함. 원래 후보명은 Kyber·Dilithium·SPHINCS+였음.
- **비유**: 도시 전체가 "원형 자물쇠"만 쓰는데 그 자물쇠만 따는 만능 도구가 곧 나온다는 소문이 도는 상황임. 자물쇠를 전혀 다른 원리(격자 미로)로 바꾸되, 당장은 원형+미로 이중 자물쇠(하이브리드)를 병용해 어느 쪽이 뚫려도 버티게 함.
- **구체 예시**: 최신 브라우저·서버는 이미 TLS 키교환에 X25519MLKEM768 하이브리드를 적용해 기존 ECDHE와 ML-KEM을 동시에 씀 — 둘 중 하나만 안전해도 세션키가 지켜짐(013·014 확장). 격자는 키·서명 크기가 RSA/ECC보다 커 대역폭·성능 영향을 검토해야 함.
- **흔한 오해·주의점**: (1) "양자컴퓨터가 아직 없으니 급하지 않다"는 오해 — HNDL 때문에 장기 보존 데이터는 지금 전환해야 함. (2) PQC는 양자컴퓨터로 도는 암호가 아니라 고전 컴퓨터에서 도는 양자내성 암호임(QKD 020과 구분). (3) 대칭키·해시는 폐기 대상이 아니라 키 길이 상향으로 대응함.

## 연결 개념
- ML-KEM·ML-DSA·SLH-DSA — 표준화된 PQC 알고리즘 상세 (016~018 참조)
- PQC 전환·하이브리드 — 인벤토리·우선순위·이중키 로드맵 (019 참조)
- 양자키분배(QKD) — 물리 기반 키분배로 PQC와 접근이 다름 (020 참조)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PQC는 Shor 알고리즘으로도 못 깨는 격자 등 난제 기반 공개키 암호로, NIST FIPS 203/204/205로 표준화됨.
> 2. **가치**: RSA·ECC를 대체해 CRQC 시대의 키교환·서명을 지키고, HNDL 위협을 받는 장기 데이터를 지금부터 보호함.
> 3. **판단 포인트**: 즉시 전면 교체는 위험이 커, 하이브리드 병용과 암호 민첩성으로 단계 전환하는 것이 실효 관건임.

| 표준 이해 확인 | FIPS 203/204/205·격자기반 | 표준명·번호 오기 |

> 요약: PQC 답안은 Shor·HNDL 위협·NIST FIPS 203/204/205 표준·하이브리드 전환 전략을 함께 정확히 써야 함.

## Ⅰ. 개요 및 필요성

- 개요: 양자컴퓨터로도 못 푸는 난제에 기반한 양자내성 공개키 암호임.
- 배경: RSA·ECC는 Shor 알고리즘으로 무력화되며, 대칭키·해시는 Grover로 강도가 절반이 됨.
- 필요성: HNDL 공격으로 장기 보존 데이터가 현재부터 위험해 조기 전환과 표준 채택이 필요함.
- 전제: 개별 알고리즘·전환 로드맵은 (016~019 참조)로 위임하고 위협·난제·표준·전환 전략에 집중함.

---

## Ⅱ. 구조 및 구성요소

```text
양자 위협: Shor(RSA·ECC 파괴) / Grover(대칭키 강도 절반)
  -> PQC 난제군
       / 격자기반(Module-LWE): ML-KEM(키교환)·ML-DSA(서명)
       / 해시기반: SLH-DSA(서명)
       / 코드·다변수 등 기타 후보
  -> NIST 표준: FIPS 203 / 204 / 205
  -> 적용: 하이브리드(ECDHE+ML-KEM) -> 인증서·KMS·프로토콜 전환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Shor·Grover | 위협 원천(공개키 파괴·대칭 약화) | 공개키는 대체, 대칭은 길이 상향 |
| 격자기반 | 주력 PQC 난제(Module-LWE) | ML-KEM·ML-DSA의 기반 |
| FIPS 203 ML-KEM | 표준 키 캡슐화 | 키교환 용도, Kyber 기반 |
| FIPS 204 ML-DSA | 표준 서명 | 서명 용도, Dilithium 기반 |
| FIPS 205 SLH-DSA | 해시기반 서명 | 격자 불신 시 대안, SPHINCS+ |
| 하이브리드 | 기존+PQC 병용 | 전환기 안전판·암호 민첩성 |

> 요약: 양자 위협에 맞서 격자·해시 기반 난제로 ML-KEM·ML-DSA·SLH-DSA를 표준화하고, 하이브리드로 단계 적용함.

---

## Ⅲ. 동작원리 및 흐름도

```text
공격자: 현재 ECDHE/RSA 암호문 수집·저장(HNDL)
미래: CRQC + Shor -> 저장 암호문 복호 시도
방어: 데이터 인벤토리 -> 보호기간·노출도 우선순위
  -> 취약구간 하이브리드(ECDHE+ML-KEM) 적용 -> 표준 PQC 전면 전환
```

1. 공격자가 현재 통신·저장 암호문을 수집해 두었다가 미래 CRQC로 복호를 노리는 것이 HNDL 위협임.
2. 조직이 RSA·ECDH·ECDSA 사용처를 암호 인벤토리로 식별하고 보호기간·외부 노출도로 우선순위를 정함.
3. 우선구간부터 ECDHE+ML-KEM 같은 하이브리드로 전환해 기존·PQC 중 하나만 안전해도 세션이 보호되게 함.
4. 이후 인증서·KMS·코드서명·VPN을 FIPS 203/204/205 기반으로 순차 전면 전환하며 암호 민첩성을 확보함.

> 요약: HNDL 위협을 전제로 인벤토리·우선순위·하이브리드·전면 전환의 순으로 진행하며 어느 한쪽 파훼에도 견디게 설계함.

---

## Ⅳ. 특징

- 난제 전환: 소인수분해·이산로그가 아닌 격자(Module-LWE)·해시 등 양자내성 난제에 안전성을 둠.
- 고전 실행: 양자컴퓨터가 아닌 일반 컴퓨터에서 동작하는 소프트웨어 알고리즘임(QKD와 구분).
- 표준 확립: NIST가 FIPS 203(ML-KEM)·204(ML-DSA)·205(SLH-DSA)를 2024년 확정해 채택 근거를 제공함.
- 크기·성능 부담: 격자 기반은 키·서명 크기가 RSA/ECC보다 커 대역폭·핸드셰이크 성능 검토가 필요함.
- 하이브리드 병용: 전환기에는 기존+PQC를 동시 사용해 신규 알고리즘 결함 위험을 분산함.
- 대칭·해시 보존: 폐기가 아니라 AES-256·SHA-384↑로 키 길이를 상향해 Grover에 대응함.

---

## Ⅴ. 심화 비교 및 적용 판단

기존 공개키(RSA·ECC)와 PQC를 안전근거·양자내성·크기 축으로 비교함(다대상×다축이므로 표 사용).

| 구분 | RSA/ECC | PQC(격자기반) |
|:---|:---|:---|
| 안전 근거 | 소인수분해·이산로그 | 격자 최단벡터·Module-LWE |
| 양자내성 | Shor로 파훼 | 현재까지 양자내성 |
| 키·서명 크기 | 작음(수백 바이트) | 큼(수 KB) |
| 표준·성숙도 | 수십 년 검증 | 2024 표준화, 상대적 신생 |

> 요약: 장기 보호·대외 데이터는 하이브리드로 선전환하고, 성숙도 불안은 하이브리드 병용과 암호 민첩성으로 흡수함.

리스크 관리는 불릿으로 정리함.
- 리스크: HNDL 노출 — 원인: 장기 데이터가 RSA/ECDH로만 보호 — 대응: 우선구간 하이브리드 조기 적용, 미전환 장기데이터 최소화.
- 리스크: 신규 알고리즘 결함 — 원인: PQC 검증기간 짧음 — 대응: 기존+PQC 하이브리드 병용, 단독 PQC 의존 회피.
- 리스크: 전환 누락 — 원인: 임베디드·협력사 API 등 숨은 사용처 — 대응: 암호 인벤토리·crypto agility 설계, 미식별 사용처 0건.

지표 관리도 불릿으로 정리함.
- 지표: 전환 진척률 — 목표: 우선구간 하이브리드 적용률 — 측정: 암호 인벤토리 대비 전환 현황.
- 지표: 표준 준수 — 목표: FIPS 203/204/205 채택 — 측정: 알고리즘 구성 감사.
- 지표: 암호 민첩성 — 목표: 알고리즘 교체 소요 단축 — 측정: 교체 리드타임 측정.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 인벤토리·우선순위: RSA·ECDH·ECDSA 사용처를 목록화하고 보호기간·외부 노출도로 전환 우선순위 결정(019).
2. 하이브리드 적용: TLS 키교환을 X25519+ML-KEM-768로 병용하고 대칭키는 AES-256·해시는 SHA-384↑로 상향.
3. 표준·민첩성: FIPS 203/204/205 기반 라이브러리·HSM·인증서로 전환하며 알고리즘 교체가 쉬운 암호 민첩성 설계.

**결론 (2줄):**
- 기술사 판단: 장기 보존·대외 노출 데이터는 지금 하이브리드로 선전환하고, 나머지는 표준 성숙도에 맞춰 단계 이행함.
- 향후 방향: 하이브리드에서 순수 PQC로의 이행과 암호 민첩성 확보로 CRQC 등장에 상시 대응이 필요함.
