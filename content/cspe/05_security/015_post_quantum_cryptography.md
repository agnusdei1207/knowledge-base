## 미리 알고가기

- PQC: 양자컴퓨터 공격을 고려해 설계한 수학적 난제 기반 공개키 암호임
- 쇼어 알고리즘: RSA, DH, ECC의 기반 난제를 다항 시간에 푸는 양자 알고리즘임
- HNDL: 지금 암호문을 수집하고 나중에 양자컴퓨터로 해독하려는 위협 가정임
- KEM: 공개키 기반으로 공유 비밀을 캡슐화하는 방식임
- Crypto Agility: 알고리즘 교체가 가능하도록 암호 사용 지점을 모듈화하는 설계 원칙임

## Ⅰ. 개요

- **정의/개념**: PQC는 양자컴퓨터의 알려진 공격을 고려해 격자, 해시, 코드 등 난제 기반으로 설계한 공개키 암호군임
- **배경/필요성**: RSA·DH·ECC는 쇼어 알고리즘 영향 대상임. 장기 기밀성과 인증 체계를 유지하려면 전환 계획이 필요함

## Ⅱ. 특징

- PQC는 양자 채널이 아니라 일반 컴퓨터와 네트워크에서 동작하는 알고리즘임
- 키 교환은 KEM, 신원 확인은 전자서명 알고리즘으로 역할이 나뉨
- 알고리즘마다 공개키, 암호문, 서명 크기가 달라 프로토콜 영향이 다름
- 전환은 알고리즘 교체만이 아니라 자산 식별과 호환성 검증을 포함함

## Ⅲ. 종류 및 비교

| 구분 | ML-KEM | ML-DSA | SLH-DSA |
|:---|:---|:---|:---|
| 역할 | 키 캡슐화 | 전자서명 | 해시 기반 전자서명 |
| 기반 | 모듈 격자 난제 | 모듈 격자 난제 | 해시 함수 |
| 적용 | TLS 키 교환, VPN | 인증서, 코드 서명 | 장기 보수 서명 |
| 운영 변수 | 공개키·암호문 크기 | 서명·공개키 크기 | 큰 서명 크기 |
| 판단 기준 | 세션키 합의 전환 | 인증 생태계 전환 | 보수적 대안 필요성 |

> 요약: PQC는 하나의 알고리즘이 아니라 KEM과 서명 역할별 표준을 조합해 전환함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 암호 자산 목록 | 시스템 안의 RSA, DH, ECC 사용 지점 식별 |
| PQC KEM | 세션키 합의를 PQC 기반으로 대체 |
| PQC 서명 | 인증서와 코드 서명의 장기 신뢰 대체 |
| 하이브리드 방식 | 기존 알고리즘과 PQC를 함께 적용해 전환 위험 완화 |
| 성능·호환성 검증 | 메시지 크기, 지연, 중간 장비 영향 확인 |

```text
암호 자산 식별 -> 위험 우선순위 -> 하이브리드 적용 -> 검증 -> 단독 전환
```

## Ⅴ. 원리 및 절차 흐름도

1. **자산 식별**: 인증서, TLS, VPN, 코드 서명, 라이브러리 사용 지점을 찾음
2. **위험 평가**: 데이터 보존 기간과 HNDL 영향을 기준으로 우선순위를 정함
3. **하이브리드 적용**: 기존 KEX·서명과 PQC 알고리즘을 함께 운용함
4. **호환성 검증**: MTU, 인증서 체인, 중간 장비, 성능 지표를 측정함
5. **전환 확대**: 정책과 라이브러리 지원에 맞춰 PQC 적용 범위를 넓힘

## Ⅵ. 실무 적용 및 유의점

- 장기 기밀 데이터는 HNDL 위험 때문에 키 교환 전환 우선순위가 높음
- 인증서와 코드 서명은 검증 생태계 준비가 늦으면 서비스 장애가 발생함
- 하이브리드는 두 알고리즘 결과 결합 방식과 실패 처리 정책을 명확히 해야 함
- PQC 메시지 크기는 TLS 레코드, MTU, 로드밸런서 제한에 영향을 줄 수 있음
- QKD는 물리적 키 분배 기술이므로 PQC와 적용 계층이 다름

## Ⅶ. 결론

- PQC의 중심 절차는 양자 위협에 맞춘 KEM·서명 표준을 기존 인프라에 단계적으로 넣는 것임
- 답안에서는 “양자에도 안전”이라는 단정 대신 위협 대상, 알고리즘 역할, 전환 절차를 써야 함
