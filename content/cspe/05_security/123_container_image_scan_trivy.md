## 미리 알고가기

- 컨테이너 이미지는 애플리케이션과 실행에 필요한 패키지를 묶은 배포 단위임
- CVE는 공개된 보안 취약점 식별 번호임
- Trivy는 이미지, 파일시스템, IaC를 함께 점검할 수 있는 오픈소스 스캐너임

## Ⅰ. 개요

- **정의/개념**: 컨테이너 이미지 취약점 스캔은 배포 전에 이미지 안의 취약 패키지, 노출 비밀, 잘못된 설정을 찾아 위험한 산출물의 반입을 막는 점검 절차이며 Trivy는 이를 수행하는 대표 도구임
- **배경/필요성**: 운영 환경에서 취약 이미지를 뒤늦게 고치는 것보다 빌드 단계에서 막는 편이 훨씬 빠르고 비용이 적으므로 배포 전 검사가 기본 통제로 자리 잡음

## Ⅱ. 특징

- 이미지를 실행하지 않고 레이어를 분석해 패키지와 설정을 정적으로 점검함
- 운영체제 패키지와 언어별 라이브러리와 비밀 노출을 함께 볼 수 있음
- CI 파이프라인에 넣기 쉬워 배포 게이트로 쓰기 적합함
- 취약점 개수만 세면 우선순위가 흔들리므로 실제 사용 여부와 수정 가능성까지 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 이미지 스캔 | 런타임 탐지 |
|:---|:---|:---|
| 보는 시점 | 배포 전 | 배포 후 |
| 주된 대상 | 취약 패키지, 비밀, 잘못된 이미지 설정 | 실행 중 프로세스와 파일과 네트워크 행위 |
| 강점 | 위험한 이미지를 초기에 차단함 | 사전 검사를 통과한 뒤 생기는 이상행위를 찾음 |
| 함께 필요한 이유 | 들어오기 전 거름 | 들어온 뒤 감시 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이미지 분석기 | 레이어를 열어 운영체제 패키지와 라이브러리 목록을 추출함 |
| 취약점 데이터베이스 | 추출한 버전과 CVE 정보를 대조함 |
| 비밀·설정 점검 | 토큰, 키, 잘못된 Dockerfile 설정, IaC 오류를 함께 찾음 |
| 정책 게이트 | 치명도와 예외 기준에 따라 빌드 실패 여부를 결정함 |
| 결과 보고 | SBOM, 취약점 목록, 수정 권고를 출력함 |

```text
이미지 빌드 -> 레이어 분석 -> CVE/비밀/설정 점검 -> 정책 판정 -> 배포 허용 또는 차단
```

## Ⅴ. 원리 및 절차 흐름도

```text
이미지 생성 -> 패키지 추출 -> 취약점·비밀 대조 -> 정책 적용 -> 통과 이미지 배포
```

1. **이미지 생성**: 애플리케이션 이미지를 빌드함
2. **패키지 추출**: 레이어 안의 운영체제와 라이브러리 버전을 읽음
3. **위험 대조**: CVE와 비밀 노출과 잘못된 설정을 찾음
4. **정책 적용**: 치명 취약점이나 노출 비밀이 있으면 빌드를 멈춤
5. **배포 승인**: 통과한 이미지만 레지스트리와 배포 단계로 넘김

## Ⅵ. 실무 적용 및 유의점

1. CI 파이프라인에서는 치명 취약점과 비밀 노출이 있는 이미지를 바로 막아야 하며 빌드 차단 건수와 운영 배포 전에 제거된 치명 취약점 수로 확인함
2. 취약점 데이터베이스가 오래되거나 예외가 누적되면 스캔 결과가 무뎌지므로 데이터 갱신 시각과 임시 예외 만료 초과 건수로 점검함

## Ⅶ. 결론

- 이미지 스캔은 운영 사고 뒤의 수습보다 훨씬 앞단에서 위험을 끊는 통제이므로 배포 게이트와 예외 관리까지 함께 설계해야 함
