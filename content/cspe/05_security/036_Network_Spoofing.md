## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 공격자가 자신의 신원(MAC, IP, DNS 등)을 속여 정상적인 시스템인 것처럼 위장해 네트워크 트래픽을 가로채거나 변조하는 기법임 |
| **배경/필요성** | 초기 인터넷 프로토콜들이 상호 인증 없이 단순히 주소만 믿고 통신하도록 취약하게 설계된 근본적 원인에서 기인함 |
| **출제 의도** | OSI 7계층별 식별자 위조 방식(L2: ARP, L3: IP, L7: DNS)의 공격 원리와 대응책 평가 |

## Ⅱ. 구성요소
```text
+-------------------+      +-------------------+      +-------------------+
|   ARP Spoofing    |      |    IP Spoofing    |      |   DNS Spoofing    |
| (L2 MAC 주소 위조)+----->| (L3 IP 주소 위조) +----->| (L7 도메인 위조)  |
+-------------------+      +-------------------+      +-------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| **ARP 스푸핑 (L2)** | 로컬망에서 피해자의 ARP 캐시 테이블을 오염시켜, 게이트웨이(라우터)의 MAC 주소를 공격자의 MAC으로 속임 | 가짜 이정표를 세워 우편물을 엉뚱한 집으로 배달 |
| **IP 스푸핑 (L3)** | 패킷의 출발지 IP 주소를 신뢰받는 내부 IP나 임의의 주소로 위조하여 방화벽이나 인증을 우회함 | 편지 봉투의 발신자 이름(송신처)을 가짜로 적기 |
| **DNS 스푸핑 (L7)** | 피해자가 특정 도메인(예: bank.com) 접속 시, 공격자가 가짜 IP 주소를 먼저 응답해 피싱 사이트로 유도함 | 114 안내원이 가짜 은행 전화번호를 알려줌 |

> 요약: 통신 계층별로 신원을 증명하는 고유 주소 체계의 맹점을 파고들어 정보의 흐름을 통째로 훔치는 공격임.

## Ⅲ. 절차
```text
+----------------+   +----------------+   +----------------+   +----------------+
| 1. 위조 패킷   |-->| 2. 테이블 오염 |-->| 3. 트래픽 탈취 |-->| 4. 정보 변조   |
| (Broadcast/응답)|  | (Cache/Routing) |  | (MITM 공격)    |   | (피싱/스니핑)  |
+----------------+   +----------------+   +----------------+   +----------------+
```
1. **위조 패킷 전송**: 공격자가 위조된 MAC, 출발지 IP 또는 가짜 DNS 응답 패킷을 피해자나 라우터로 전송함
2. **캐시/테이블 오염**: 인증 로직이 없는 피해자 PC나 라우터가 수신한 가짜 정보를 그대로 자신의 캐시/라우팅 테이블에 업데이트함
3. **트래픽 탈취**: 피해자가 외부와 통신하려 할 때, 오염된 정보를 바탕으로 트래픽이 공격자 서버를 경유(MITM)하게 됨
4. **정보 변조/피싱**: 공격자는 트래픽을 도청(스니핑)하여 패스워드를 탈취하거나, 가짜 금융 사이트로 리다이렉트 시킴

> 요약: 신뢰 기반 프로토콜에 가짜 응답을 밀어 넣어 피해자의 통신 경로를 장악하는 흐름임.

## Ⅳ. 문제점
* **근본적 프로토콜의 취약성**: ARP, IP, DNS 등 초기 인터넷 프로토콜 자체에 서명이나 상호 인증 메커니즘이 전혀 없어 근본적 방어 불가
* **MITM 및 도청의 치명성**: 스푸핑을 통해 중간자 공격(MITM)에 성공하면, 평문 통신 시 패스워드와 기밀문서가 고스란히 탈취됨
* **역추적의 어려움**: IP 스푸핑 등은 출발지 주소가 완벽히 위조되므로 로그를 분석하더라도 실제 해커의 위치를 찾기 어려움

## Ⅴ. 개선방안
* **단기 방안 (정적 테이블 및 스누핑)**: L2 스위치에 정적 ARP 테이블을 매핑하거나, DHCP Snooping 및 Dynamic ARP Inspection(DAI) 설정 적용
* **중기 방안 (IP 필터링 및 TLS 적용)**: 방화벽에 Ingress/Egress 필터링을 적용해 위조 IP 차단, 웹 통신은 HTTPS(TLS)를 강제해 피싱 사이트 판별
* **장기 방안 (DNSSEC 및 프로토콜 개선)**: DNS 응답에 전자서명을 추가하는 DNSSEC 도입, 차세대 보안 프로토콜 규격으로 점진적 마이그레이션

## Ⅵ. 전망
* 단순 평문 도청은 HTTPS, SSH 보편화로 무력화되었으나, 세션 하이재킹과 결합한 파밍(Pharming) 등 지능형 스푸핑으로 고도화됨
* 제로 트러스트(ZTA) 도입으로 '단순한 IP/MAC 주소' 자체를 신뢰하지 않고, 암호학적 기기 인증을 필수화하는 아키텍처로 나아감
