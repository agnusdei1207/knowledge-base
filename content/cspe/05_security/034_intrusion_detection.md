# 📖 【암기용】 개념 완전 이해

> 목적: 침입 탐지를 서명 기반과 이상 탐지 기준으로 구분해 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 시스템·네트워크에서 정상 행위와 다른 공격 징후를 찾아 경보로 전환하는 보안 분석 과정
- **왜 필요한가**: 모든 공격을 사전에 차단할 수 없으므로, 침입 발생 전후의 징후를 MTTD 10분 목표로 발견해 피해 범위를 줄여야 한다.
- **핵심 직관**: 이미 알려진 범죄 수법을 찾는 지명수배 방식과 평소와 다른 행동을 찾는 이상 행동 분석을 함께 쓰는 개념이다.

## 깊이 이해
- **배경·문제의식**: 방화벽과 접근통제가 있어도 계정 탈취, 내부 이동, 제로데이, 파일리스 공격은 허용된 경로로 진행될 수 있다. 침입 탐지는 로그·패킷·호스트 이벤트에서 공격 단계를 추적함.
- **작동 원리**: 서명 기반은 알려진 공격 패턴과 비교해 탐지한다. 이상 탐지는 정상 기준선과 다른 빈도, 시간, 경로, 명령 실행을 점수화한다. 실제 운영은 두 방식을 SIEM, EDR, NDR에서 결합함.
- **비유**: 서명 기반은 위조지폐 판별기처럼 알려진 특징을 찾고, 이상 탐지는 카드사가 평소와 다른 결제 장소와 금액을 탐지하는 방식임.
- **구체 예시**: 평소 09시~18시 서울 IP에서 접속하던 계정이 03시에 해외 ASN에서 500건 파일 다운로드를 수행하면 이상 탐지가 우선 경보를 생성하고, 이후 DLP·CASB 로그와 연계함.
- **흔한 오해·주의점**: 이상 탐지가 서명 기반을 대체하지 않음. 알려진 CVE 공격은 시그니처가 낮은 지연으로 탐지하고, 신규·내부자 행위는 이상 탐지로 보완함.

## 연결 개념
- IDS/IPS: 침입 탐지를 네트워크 센서와 차단 장치로 구현
- SIEM: 로그 상관분석과 경보 관리
- MITRE ATT&CK: 공격 전술·기법 기반 탐지 룰 설계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 침입 탐지 답안은 시그니처와 이상 탐지 차이를 탐지율, 오탐율, 데이터 소스, 대응 시간으로 평가해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 침입 탐지는 네트워크·호스트·계정·애플리케이션 행위에서 공격 징후를 식별해 경보와 대응 절차로 연결하는 과정이다.
> 2. **가치**: 서명 기반은 알려진 공격을 정밀 탐지하고, 이상 탐지는 미지 공격·내부자 행위를 기준선 이탈로 포착한다.
> 3. **판단 포인트**: 탐지율, 오탐율, 평균탐지시간 MTTD, 로그 품질을 함께 봐야 실무 적용 가능함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 침입 탐지 방식 이해 확인 | signature, anomaly, hybrid, behavior baseline | 탐지 도구명만 나열 |
| 정량 지표 판단 확인 | 탐지율, 오탐율, 미탐율, MTTD, MTTR | "정확하다" 같은 추상 표현 사용 |
| 운영 연계 확인 | 로그 수집, 상관분석, 대응 playbook | 경보 생성 이후 triage와 대응 누락 |

> 요약: 침입 탐지 문제는 탐지 방식보다 데이터 품질과 오탐·미탐 관리 지표를 요구함.

---

## Ⅰ. 개요 및 필요성

- 개요: 공격 징후를 경보로 전환하는 분석
- 배경: 계정 탈취, 내부 이동, 제로데이 공격은 허용된 로그인·프로세스·네트워크 경로를 이용해 차단 정책을 우회함.
- 필요성: 탐지 체계는 로그 손실 1% 이하, MTTD 10분, MTTR 60분 목표로 수집·기준선·경보 검증·대응 절차를 연결해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Network/Host/Cloud Logs -> Collection -> Normalization -> Detection Engine
                           +-> Signature Rules / Anomaly Model / Threat Intel
Detection Alert -> Triage -> SIEM/SOAR -> Response
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Data Source | 패킷, EDR, IAM, DB, Cloud audit 로그 수집 | 시간 동기화 NTP 필수 |
| Detection Rule | 서명·상관분석·행위 기준 적용 | CVE, ATT&CK technique 매핑 |
| Baseline Model | 정상 접속 시간·위치·명령 빈도 학습 | 30일 이상 기준선 권장 |
| Response Workflow | triage, 격리, 티켓, 보고 수행 | SOAR playbook, SLA 연결 |

> 요약: 침입 탐지는 데이터 소스, 탐지 규칙, 기준선, 대응 절차가 연결되어야 작동함.

---

## Ⅲ. 동작원리 및 흐름도

```text
Event 수집 -> 정규화 -> Signature 매칭 / Baseline 비교
-> Risk Score 계산 -> Alert 생성 -> Analyst Triage -> Response
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 로그·패킷·호스트 이벤트 수집 | log loss 1% 이하, NTP 오차 1초 이하 |
| 2 | 정규화와 자산 중요도 태깅 | CMDB, user identity 매핑률 95% |
| 3 | 서명·이상 탐지 룰 적용 | 탐지율 95% 이상, 오탐율 5% 이하 |
| 4 | 경보 triage와 대응 실행 | MTTD 10분, MTTR 60분 목표 |

> 요약: 침입 탐지는 이벤트를 정규화한 뒤 규칙과 기준선 비교로 위험 점수를 만들고 대응으로 연결함.

---

## Ⅳ. 특징

| 구분 | 서명 기반 | 이상 탐지 | 판단 포인트 |
|:---|:---|:---|:---|
| 탐지 대상 | 알려진 CVE, 악성 패턴 | 신규 공격, 내부자, 계정 오남용 | 지식 기반과 행위 기반 병행 |
| 장점 | 룰 해석 가능, 오탐 조정 용이 | 알려지지 않은 행위 포착 | 기준선 데이터 30일 이상 필요 |
| 한계 | 제로데이 미탐 | 오탐 발생 가능 | false positive 5% 이하 튜닝 |
| 지표 | signature hit, CVE coverage | anomaly score, drift rate | 탐지율·오탐율 동시 관리 |

> 요약: 서명 기반은 알려진 공격, 이상 탐지는 기준선 이탈을 담당하므로 혼합 탐지가 필요함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 장비 경보 | 로그·패킷·호스트 통합 탐지 | 공격 단계별 kill chain 추적 필요 시 |
| 비용/성능 | 룰 기반만 운영 | 룰+행위 분석+위협 인텔 | 분석가 1인당 daily alert 50건 이하 |
| 운영/위험 | 경보 과다 | risk score 기반 우선순위 | critical alert SLA 10분 이내 triage |

> 요약: 침입 탐지는 도구 수보다 경보 우선순위와 분석가 처리 용량으로 적용성을 판단함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 경보 피로 | 낮은 품질 룰, 중복 이벤트 | 룰 병합, severity 조정, suppression | analyst당 daily alert 50건 이하 |
| 미탐 | 로그 누락, 기준선 부재 | 필수 로그 목록, 30일 baseline, purple team | ATT&CK coverage 80% 이상 |
| 오탐 | 업무 이벤트 오분류 | allowlist 만료일, 모델 재학습 | false positive 5% 이하 |

> 요약: 탐지 운영의 핵심 리스크는 경보 피로와 미탐이며, ATT&CK 커버리지와 오탐율로 관리함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지 품질 | 탐지율 95% 이상, 오탐율 5% 이하 | 모의침투, red/purple team |
| 데이터 품질 | 필수 로그 수집률 99%, ID 매핑률 95% | SIEM ingestion report |
| 대응 시간 | MTTD 10분, MTTR 60분 | 사고 티켓 타임라인 |

> 요약: 침입 탐지 성과는 탐지 정확도, 로그 품질, 대응 시간의 세 축으로 평가함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 데이터 설계: 방화벽, IDS/IPS, EDR, IAM, DB audit, CloudTrail 로그를 SIEM으로 수집하고 NTP 오차 1초 이하 유지
2. 탐지 룰 설계: MITRE ATT&CK 기준으로 initial access, privilege escalation, lateral movement 룰을 우선 구축
3. 운영 튜닝: 30일 기준선 학습, false positive 5% 이하까지 튜닝, critical 경보는 SOAR로 계정 잠금·호스트 격리 수행

**결론 (2줄):**
- 기술사 판단: 알려진 취약점 공격은 서명 기반, 계정 탈취·내부 이동은 이상 탐지와 상관분석을 적용함
- 향후 방향: 탐지 공학은 룰 작성에서 ATT&CK coverage, MTTD, MTTR을 지표화하는 지속 개선 체계로 전환해야 함
