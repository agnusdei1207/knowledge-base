## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 소프트웨어 개발 시 보안 취약점을 사전에 예방하기 위한 코딩 규칙·점검 기준의 체계적 지침임 |
| **배경/필요성** | 개발 단계에서 취약점을 제거하는 비용이 운영 단계 대비 1/30 수준이며, 행안부 시큐어코딩 의무화로 공공 SW에 필수 적용됨 |
| **출제 의도** | 시큐어 코딩 7대 유형과 SW 개발 생명주기 내 적용 시점을 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 입력검증  | --> | 보안기능  | --> | 에러처리  |
| (Input)  |     | (Auth)   |     | (Error)  |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 입력 데이터 검증 | 외부 입력의 유효성·안전성을 서버측에서 검증하여 인젝션을 차단함 | 공항 보안 검색대 |
| 보안 기능 | 인증·암호화·접근 제어 등 보안 메커니즘을 올바르게 구현함 | 금고의 잠금장치 |
| 에러 처리 | 예외 발생 시 민감 정보(스택 트레이스 등)를 외부에 노출하지 않음 | 내부 사정을 외부에 비공개 |

> 요약: 입력 검증·보안 기능·에러 처리를 핵심 축으로 개발 단계에서 취약점을 원천 차단함.

## Ⅲ. 절차
```
+------------+     +------------+
| 요구사항   | --> | 설계단계   |
| 보안분석   |     | 위협모델링  |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 배포후     | <-- | 구현단계   |
| 보안검증   |     | 시큐어코딩 |
+------------+     +------------+
```

1. 보안 요구사항 정의: 개인정보 처리·인증 수준 등 보안 요구를 명세서에 반영함
2. 위협 모델링: STRIDE 등으로 설계 단계에서 위협을 식별하고 대응책을 수립함
3. 시큐어 코딩 적용: 행안부 7대 유형(입력검증, 보안기능, 시간/상태 등) 기준으로 코딩함
4. 보안 검증: SAST·DAST 도구로 취약점을 점검하고, 코드 리뷰를 통해 잔여 결함을 제거함

> 요약: 요구사항 → 설계 → 구현 → 검증 전 단계에 보안 활동을 내재화함.

## Ⅳ. 문제점
- 개발자 보안 인식 부족: 기능 구현 우선 문화에서 보안 코딩이 후순위로 밀림
- 레거시 코드 적용 한계: 기존 대규모 코드베이스에 소급 적용 시 비용·일정 부담이 큼
- 도구 오탐: SAST 도구의 높은 오탐율(False Positive)로 개발자 피로도가 증가함

## Ⅴ. 개선방안
- (단기) 교육 의무화: 신규 입사자·프로젝트 착수 시 시큐어 코딩 교육을 필수로 이수함
- (중기) IDE 플러그인 연동: 개발 환경에 SAST를 실시간 통합하여 코딩 시점에 즉시 피드백함
- (장기) AI 기반 코드 리뷰: LLM 기반 코드 리뷰 봇이 PR 단계에서 취약 패턴을 자동 탐지·제안함

## Ⅵ. 전망
- GitHub Copilot·CodeQL 등 AI 기반 보안 분석이 CI/CD에 기본 내장되며, DevSecOps 파이프라인에서 시큐어 코딩 검증이 자동화될 전망임
