## Ⅰ. 개요
| 항목 | 내용 |
|---|---|
| **정의** | 힙에서 해제(free)된 메모리를 가리키는 댕글링 포인터를 통해 재접근할 때 발생하는 메모리 오염 취약점임 |
| **배경/필요성** | 브라우저·커널 등 대규모 C/C++ 프로젝트에서 객체 생명주기 관리 오류가 빈발하며, CVE의 상위 취약점 유형임 |
| **출제 의도** | 힙 메모리 관리 오류의 원리와 댕글링 포인터 악용 시나리오를 이해하는지 평가함 |

## Ⅱ. 구성요소
```
+----------+     +----------+     +----------+
| 힙 할당   | --> | 힙 해제   | --> | 댕글링   |
| (malloc) |     | (free)   |     | 포인터   |
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|---|---|---|
| 힙 할당 | `malloc`/`new`로 동적 메모리를 할당하여 객체를 생성함 | 호텔 방 체크인 |
| 힙 해제 | `free`/`delete`로 메모리를 반환하나, 포인터 변수는 그대로 남음 | 체크아웃 후 카드키 미회수 |
| 댕글링 포인터 | 해제된 메모리를 여전히 가리키는 포인터로, 재사용 시 오염 발생함 | 회수 안 된 카드키로 타인 방 출입 |

> 요약: 해제 후 포인터 미초기화로 댕글링 포인터가 남아 힙 메모리 재접근이 가능해짐.

## Ⅲ. 절차
```
+------------+     +------------+
| 객체할당   | --> | 객체해제   |
| (A=new X)  |     | (delete A) |
+------------+     +------------+
                        |
+------------+     +----+-------+
| 임의코드   | <-- | 동일크기  |
| 실행       |     | 재할당점유 |
+------------+     +------------+
```

1. 객체 할당: 힙에 객체를 생성하고 포인터 A가 해당 주소를 참조함
2. 객체 해제: `free(A)` 호출 후 포인터 A를 NULL로 초기화하지 않음
3. 힙 재할당: 공격자가 동일 크기의 객체를 할당하여 해제된 메모리 영역을 점유함
4. 댕글링 접근: 기존 포인터 A를 통해 공격자가 배치한 데이터(가상 함수 테이블 등)에 접근하여 코드를 실행함

> 요약: 할당 → 해제(미초기화) → 재할당 점유 → 댕글링 접근으로 실행 흐름을 탈취함.

## Ⅳ. 문제점
- 탐지 난이도: 해제 시점과 재접근 시점이 코드상 멀리 떨어져 정적 분석으로 발견이 어려움
- 브라우저 취약점 비중: Chrome·Firefox CVE의 약 70%가 UAF 유형이며 공격 가치가 높음
- 커널 UAF: 리눅스 커널의 슬랩 할당기에서 UAF 발생 시 권한 상승(LPE)으로 직결됨

## Ⅴ. 개선방안
- (단기) 해제 후 NULL 대입: `free(ptr); ptr = NULL;` 패턴을 코딩 표준으로 강제함
- (중기) 스마트 포인터 도입: C++의 `unique_ptr`, `shared_ptr`로 소유권 기반 생명주기를 자동 관리함
- (장기) MiraclePtr/MarkSweep GC: Chromium의 MiraclePtr, 커널의 KASAN 등 런타임 탐지·방어 체계를 적용함

## Ⅵ. 전망
- Chromium 프로젝트의 MiraclePtr 도입과 Rust 기반 커널 모듈 전환이 가속화되며, UAF 취약점 클래스 자체를 제거하는 방향으로 발전할 전망임
