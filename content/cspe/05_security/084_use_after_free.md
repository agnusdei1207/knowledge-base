## 미리 알고가기

- 동적 메모리는 필요할 때 할당하고 사용이 끝나면 해제하는데, 해제된 메모리를 다시 참조하면 Use-after-free가 됨
- 해제 후에도 포인터 값이 남아 있으면 이미 다른 객체가 들어간 메모리를 잘못 조작할 수 있음
- 문제의 본질은 힙 생명주기 관리 실패이며 단순 충돌보다 코드 실행으로 이어질 수 있다는 점이 위험함

## Ⅰ. 개요

- **정의/개념**: Use-after-free는 이미 해제한 메모리 객체를 다시 읽거나 써서 재사용된 메모리를 오염시키는 취약점임
- **배경/필요성**: 브라우저와 커널의 C/C++ 코드는 객체 수명 관리가 복잡함. 해제 시점과 재참조 시점이 멀어 원인 파악이 어려움

## Ⅱ. 특징

- 할당, 해제, 재참조가 분리된 코드 흐름에서 자주 발생함
- 공격자는 해제된 자리에 원하는 객체를 다시 채워 넣으려 함
- NULL 참조와 달리 정상처럼 보이는 주소 접근이라 탐지와 재현이 어려움
- 스마트 포인터나 메모리 안전 언어 전환 같은 구조적 대응이 효과적임

## Ⅲ. 종류 및 비교

| 판단 기준 | Use-after-free | Double Free |
|:---|:---|:---|
| 핵심 원인 | 해제 후 재참조 | 같은 메모리를 두 번 해제 |
| 주요 피해 | 해제된 영역 재사용 오염 | 할당기 메타데이터 손상 |
| 발생 시점 | 읽기·쓰기·실행 시점 | 해제 호출 시점 |
| 기본 대응 | 소유권 관리, 포인터 무효화 | 해제 경로 통합, 중복 해제 차단 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 객체 할당 | 프로그램이 동적 메모리에 객체를 생성함 |
| 객체 해제 | free나 delete로 메모리를 반환함 |
| 댕글링 포인터 | 해제 후에도 이전 주소를 가리키는 포인터가 남음 |
| 재할당과 악용 | 다른 데이터가 같은 자리를 차지하면 오염이 발생함 |

```text
객체 생성 -> 객체 해제 -> 포인터 잔존 -> 동일 영역 재사용 -> 잘못된 재참조
```

## Ⅴ. 원리 및 절차 흐름도

```text
할당 -> 사용 -> 해제 -> 해제된 영역 재할당 -> 기존 포인터 재사용 -> 메모리 오염
```

1. **객체 할당과 사용**: 프로그램이 힙 객체를 생성해 사용함
2. **객체 해제**: 수명이 끝난 객체를 반환함
3. **포인터 잔존**: 참조값이 그대로 남아 잘못된 재사용 가능성이 생김
4. **재할당과 오염**: 다른 객체가 같은 메모리를 차지한 뒤 기존 포인터가 접근함
5. **방어 검증**: 스마트 포인터와 ASan/KASAN 적용 후 동일 경로가 차단되는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 객체 수명이 복잡한 코드베이스는 소유권 모델과 스마트 포인터를 정리하고 ASan 검증의 UAF 재현 여부·검출 건수 감소로 확인함
2. 언어 전환이 어려운 환경은 수명 추적 도구와 코드 리뷰 규칙을 두고 크래시 분류 정확도·재현 경로 제거 여부로 확인함

## Ⅶ. 결론

- Use-after-free는 해제 이후 참조가 살아 있는 구조적 문제이므로 객체 수명 관리 방식을 바꾸는 접근이 필요함
