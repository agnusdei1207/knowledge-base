# 📖 【암기용】 개념 완전 이해

> 목적: 연속 인증을 로그인 반복이 아니라 세션 위험 재평가로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 로그인 이후에도 사용자 행위, 단말, 위치, 세션 위험을 계속 평가해 접근 수준을 조정하는 인증 방식
- **왜 필요한가**: 초기 로그인만 신뢰하면 세션 탈취, 토큰 재사용, 내부자 이상 행위를 놓친다. 장시간 세션에서는 위험이 접속 중에 변한다.
- **핵심 직관**: 입장할 때 표를 한 번 보는 방식이 아니라 경기장 안에서 좌석 이동, 출입구 재진입, 이상 행동을 계속 확인하는 방식임

## 깊이 이해
- **배경·문제의식**: MFA는 로그인 순간의 신뢰를 높이지만, 로그인 후 토큰 탈취나 단말 감염을 막지는 못한다. 원격근무·SaaS 환경에서는 세션 중 컨텍스트 변화가 자주 발생한다.
- **작동 원리**: 인증 시스템은 키 입력 패턴, 마우스 움직임, 장치 지문, IP 평판, 위치 변화, 접근 리소스 민감도 등을 점수화한다. 위험 점수가 임계값을 넘으면 재인증, 권한 축소, 세션 종료를 수행한다.
- **비유**: 은행이 로그인 후에도 고액 이체, 해외 IP, 새 단말 접속을 발견하면 추가 인증을 요구하는 것과 같다.
- **구체 예시**: 사용자가 09:00 서울에서 ERP에 로그인했는데 09:20 해외 ASN에서 동일 토큰으로 접속하면 impossible travel 점수 80점을 부여하고 세션을 종료한다.
- **흔한 오해·주의점**: 연속 인증은 사용자에게 매분 OTP를 요구하는 방식이 아니다. 저위험 행위는 무마찰로 두고 고위험 이벤트에서 step-up MFA를 요구해야 한다.

## 연결 개념
- Risk-Based Authentication — 위험 점수에 따라 인증 강도를 조정
- UEBA — 사용자·엔티티 행위 기준선과 이상 탐지
- ZTNA — 세션 중 위험 변화에 따라 접근 정책을 재평가

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 연속 인증은 로그인 시점 통제를 세션 전체 통제로 확장하고 위험 점수에 따라 재인증·권한 축소·종료를 수행하는 체계임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Continuous Authentication은 초기 인증 후 행위·단말·위치·토큰 상태를 지속 평가하는 동적 신뢰 평가 모델이다.
> 2. **가치**: 세션 탈취, impossible travel, 비정상 데이터 접근을 위험 점수로 탐지해 step-up MFA 또는 세션 종료로 연결한다.
> 3. **판단 포인트**: 오탐률, 추가 인증 빈도, 탐지 지연, 사용자 이탈률을 함께 관리해야 보안 통제와 업무 연속성을 맞출 수 있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정적 인증 한계 이해 확인 | 로그인 후 토큰 탈취, 세션 위험 변화, 지속 평가 | MFA 반복으로만 설명 |
| 동적 신뢰 평가 구조 확인 | 신호 수집, 위험 점수, 정책 결정, step-up MFA | AI 이상탐지라는 단어만 나열 |
| 운영 지표 판단 확인 | 오탐률, 재인증 빈도, 탐지 지연, 개인정보 최소 수집 | 사용자 경험·프라이버시 리스크 누락 |
> 요약: 이 문제는 인증을 1회 이벤트가 아니라 세션 전체의 위험 점수 관리로 보는지 평가한다.

---

## Ⅰ. 개요 및 필요성

연속 인증은 세션 중 신뢰 재평가이다.
계정 탈취 공격은 정상 MFA 이후 토큰을 빼앗거나 장시간 세션을 악용한다. 초기 로그인만으로는 위치 변화, 단말 감염, 이상 행위를 반영하지 못한다. 따라서 세션 동안 위험 신호를 수집하고 접근 수준을 동적으로 조정해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User Session -> Signal Collector -> Risk Scoring Engine -> Policy Decision
                         +-> IdP/MFA
                         +-> UEBA/SIEM
                         +-> Session Control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Signal Collector | IP, 단말, 위치, 행위, 토큰 상태 수집 | 개인정보 최소 수집 필요 |
| Risk Scoring | 규칙·ML 기반 위험 점수 계산 | impossible travel, 신규 단말 |
| Policy Decision | 허용, step-up MFA, 권한 축소, 종료 결정 | 앱 민감도별 임계값 차등 |
| IdP/MFA | 재인증 수행과 토큰 재발급 | FIDO2, OTP, Push |
| Session Control | 세션 만료, 토큰 폐기, 감사 로그 생성 | SIEM·SOAR 연계 |
> 요약: 연속 인증은 위험 신호 수집, 점수화, 정책 결정, 세션 제어의 폐루프로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
초기 로그인 -> 세션 신호 수집 -> 위험 점수 산정
-> 임계값 비교 -> 허용 / 재인증 / 권한 축소 / 종료 -> 감사 로그
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | MFA 기반 초기 로그인 | FIDO2 성공, 토큰 발급 |
| 2 | 세션 중 신호 수집 | IP ASN, 지리 위치, 장치 지문, 행위 패턴 |
| 3 | 위험 점수 산정 | 0~100 점수, 앱별 임계값 |
| 4 | 정책 집행 | 50점 이상 step-up, 80점 이상 종료 |
| 5 | 사후 분석 | SIEM 전송, SOC 티켓 자동 생성 |
> 요약: 위험 점수가 임계값을 넘을 때만 추가 인증 또는 세션 제어를 수행해 사용자 마찰을 제한한다.

## Ⅳ. 특징

| 구분 | 정적 인증 | 연속 인증 | 정량·기술 포인트 |
|:---|:---|:---|:---|
| 평가 시점 | 로그인 1회 | 세션 전체 | 5분 주기 또는 이벤트 기반 평가 |
| 입력 신호 | ID/PW, MFA | 단말, 위치, 행위, 토큰, 앱 민감도 | 신호 5종 이상 |
| 대응 방식 | 허용 또는 거부 | 허용, step-up, 권한 축소, 종료 | 50/80점 임계값 |
| 운영 리스크 | 탈취 세션 방치 | 오탐·프라이버시 관리 필요 | 오탐률 3% 이하 |
> 요약: 연속 인증은 인증 결과를 고정하지 않고 위험 점수에 따라 세션 제어 수준을 조정한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 연속 인증 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 로그인 시 MFA | 세션 신호+위험 점수+정책 집행 | SaaS·원격 세션 8시간 이상 |
| 비용/성능 | IdP 중심 단순 로그 | UEBA·SIEM·IdP 연계 | 정책 판단 p95 150ms 이하 |
| 운영/위험 | 사용자 마찰 적음 | step-up 빈도 관리 필요 | 사용자당 일 2회 이하 추가 인증 |
> 요약: 장시간 SaaS 세션과 고위험 업무가 많으면 연속 인증이 세션 탈취 대응에 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 증가 | 행위 기준선 부족, 출장·VPN 예외 | 학습 기간 30일, 사용자 피드백 반영 | 오탐률 3% 이하 |
| 사용자 피로 | 잦은 step-up MFA | 위험 기반 임계값, 고위험 앱 한정 | 추가 인증 일 2회 이하 |
| 개인정보 과수집 | 키 입력·위치 데이터 과다 | 목적 제한, 보존 90일, 가명 처리 | 개인정보 항목 승인 100% |
> 요약: 연속 인증은 오탐, 사용자 피로, 개인정보 수집 범위를 수치 기준으로 관리해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탐지 품질 | 세션 탈취 탐지 지연 5분 이하 | UEBA, IdP, CASB 로그 |
| 사용자 영향 | step-up 성공률 98%, 포기율 1% 이하 | IdP 이벤트, Helpdesk 티켓 |
| 보안 통제 | 고위험 세션 종료 100%, 토큰 폐기 1분 이하 | SIEM, SOAR, IdP API |
> 요약: 성과는 탐지 지연, 재인증 성공률, 세션 종료·토큰 폐기 시간을 함께 확인한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 신호 설계: IP ASN, 장치 지문, EDR 상태, 위치, 앱 민감도, 행위 패턴 6종을 수집하고 보존 기간 90일 적용
2. 정책 적용: 재무·관리자 앱은 50점 step-up, 80점 세션 종료, 일반 앱은 70점 step-up으로 차등 설정
3. 운영 연계: IdP, CASB, ZTNA, SIEM 로그를 UEBA에 통합하고 SOAR로 토큰 폐기 API를 자동 호출

**결론 (2줄):**
- 기술사 판단: 고위험 SaaS·관리자 계정은 연속 인증을 적용하고, 저위험 사내 조회 업무는 위험 기반 MFA만 적용한다.
- 향후 방향: 패스키, 디바이스 바인딩 토큰, UEBA와 결합해 세션 단위 동적 접근 통제로 발전한다.
