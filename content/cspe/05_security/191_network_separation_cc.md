# 📖 【암기용】 개념 완전 이해

> 목적: 망분리와 CC 인증, 보안적합성 검증의 관계를 처음 보는 사람도 이해하게 만든다.

## 한눈에
- **개요**: 국가·공공 업무망과 인터넷망을 분리하고, 도입 제품의 보안기능을 CC 인증·보안기능확인서·보안적합성 검증으로 확인하는 체계
- **왜 필요한가**: 망을 나누어도 자료전송, 원격접속, 가상화 관리 지점이 열리면 침해 경로가 남는다. 공공기관은 제품 도입 전 인증 범위와 운용 환경까지 확인해야 한다.
- **핵심 직관**: 망분리는 벽을 세우는 일이고, CC·보안적합성은 그 벽에 설치한 문·잠금장치·출입기록이 정부 기준에 맞는지 확인하는 절차다.

## 깊이 이해
- **배경·문제의식**: 물리적 망분리는 보안성이 높지만 장비·운영비가 증가하고, 논리적 망분리는 VDI·가상화·브라우저 격리로 비용을 줄이나 하이퍼바이저와 자료전송 구간 통제가 필요하다.
- **작동 원리**: 업무망, 인터넷망, 자료전송 구간, 관리망, 로그 수집 지점을 나누고, CC 인증 또는 보안기능확인서의 TOE 범위와 국가용 보안요구사항 충족 여부를 확인한다.
- **비유**: 건물의 일반구역과 보안구역을 분리한 뒤, 출입문 카드리더와 CCTV가 인증된 장비인지 확인하고 출입기록을 감사하는 방식과 같다.
- **구체 예시**: 공공기관이 가상화 기반 망분리 제품을 도입하면 VDI 접속통제, 클립보드 차단, 파일 반입 승인, 관리자 MFA, 감사로그 보존 1년 이상을 기준으로 점검한다.
- **흔한 오해·주의점**: CC 인증 제품이라고 모든 기능이 공공 도입에 자동 적합한 것은 아니다. 인증서의 TOE 범위, 하드웨어 모델명, 암호모듈 탑재 여부, 보안적합성 검증필 목록 등재 여부를 별도로 확인해야 한다.

## 연결 개념
- CC(Common Criteria) 인증: 정보보호제품의 보안기능·보증 요구사항 평가
- 보안기능확인서: 국가용 보안요구사항 만족 여부를 시험기관이 확인한 증서
- 자료전송 통제: 망간 반입·반출 승인, 악성코드 검사, 감사로그 확보

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 공공 망분리는 제품 기능보다 인증 범위와 운용 통제를 함께 써야 점수가 난다.
> 핵심: 망분리 방식, 인증 제도, 도입 후 보안적합성 검증을 분리해 설명한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 망분리는 업무망·인터넷망·관리망을 분리하여 침해 확산 경로를 제한하는 공공 보안 아키텍처다.
> 2. **가치**: CC 인증, 보안기능확인서, 검증필 암호모듈, 보안적합성 검증으로 도입 제품의 TOE 범위와 운용 조건을 확인한다.
> 3. **판단 포인트**: 물리분리·논리분리 선택보다 자료전송, 관리자 권한, 로그 보존, 인증 유효기간이 채점 포인트다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공공 망분리 제도 이해 확인 | 국가용 보안요구사항, CC, 보안기능확인서, 보안적합성 검증 | CC 보유만으로 도입 가능하다고 단정 금지 |
| 아키텍처 설계 역량 확인 | 업무망/인터넷망/DMZ/관리망/자료전송 구간 분리 | VDI·가상화 관리면 통제 누락 금지 |
| 운영 통제 판단 확인 | 관리자 MFA, 반출 승인, 감사로그, 암호모듈 검증 | 물리분리와 논리분리 장단점만 나열 금지 |

> 요약: 출제자는 망분리 기술보다 공공 도입 절차와 인증 범위 확인 능력을 본다.

---

## Ⅰ. 개요 및 필요성

- 개요: 업무망·인터넷망 분리 통제
- 배경: 국가·공공기관은 망분리 제품 기능과 인증 범위가 다르면 침해 시 책임 소재와 감사 근거가 불명확해진다.
- 필요성: CC 인증, 보안기능확인서, 검증필 암호모듈, 보안적합성 검증 대상 여부를 도입 단계에서 확인한다.

---

## Ⅱ. 구조 및 구성요소

```text
사용자 -> 업무망 단말/VDI -> 업무시스템
사용자 -> 인터넷망 단말/브라우저 격리 -> 외부 인터넷
업무망/인터넷망 -> 자료전송 서버 -> 악성코드 검사/승인 -> 감사로그
관리자 -> 관리망 -> 정책서버/MFA/접근기록
```

| 구성요소 | 역할 | 확인 기준 |
|:---|:---|:---|
| 업무망 | 내부 업무시스템 접근 구간 | 인터넷 직접 접속 차단, 계정 RBAC |
| 인터넷망 | 외부 웹·메일 접근 구간 | 다운로드 격리, 악성코드 검사 |
| 자료전송 서버 | 망간 파일 반입·반출 통제 | 승인 워크플로, 해시, 로그 1년 이상 |
| 관리망 | 정책·패치·VDI 관리 | 관리자 MFA, 접속기록, 세션 녹화 |
| 인증·검증 체계 | 제품 안전성 확인 | CC/보안기능확인서/보안적합성 대상 확인 |

> 요약: 망분리 구조는 업무·인터넷·자료전송·관리 구간을 나누고 인증 범위와 로그로 통제한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
도입 요구 -> 제품 유형 식별 -> 인증서/확인서/암호모듈 확인
-> TOE 범위와 운용 환경 대조 -> 보안적합성 검증 여부 판단
-> 망분리 정책 적용 -> 반출 승인/로그 감사
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 제품 유형과 기관 등급 식별 | 국가용 보안요구사항, 안전성 검증필 목록 |
| 2 | 인증서 범위 확인 | TOE 기능, 하드웨어 모델, 유효기간 |
| 3 | 망분리 정책 설정 | 인터넷 차단, 클립보드 차단, 파일 전송 승인 |
| 4 | 운영 감사 | 관리자 접속, 정책 변경, 반출 로그 대조 |

> 요약: 도입 전 인증 범위 확인, 도입 후 정책 적용과 로그 감사가 하나의 절차로 묶인다.

## Ⅳ. 특징

| 구분 | 기존/대안 | 망분리 CC·보안적합성 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 격리 방식 | 방화벽 중심 경계보안 | 업무망/인터넷망/관리망 분리 | 외부 직접 접속 0건 |
| 제품 검증 | 벤더 보안 설명서 의존 | CC·보안기능확인서·검증필 목록 확인 | 인증 유효기간 5년 확인 |
| 자료 통제 | 사용자 임의 복사 | 승인 기반 반입·반출 | 반출 승인 로그 100% |
| 운영 위험 | 관리자 단일 계정 | MFA·세션기록·RBAC | 관리자 공유계정 0개 |

> 요약: 망분리는 네트워크 격리보다 인증 범위, 자료전송, 관리자 통제를 함께 충족해야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 물리분리 단말 2대 | VDI/가상화 논리분리+자료전송 통제 | 보안등급, 예산, 사용자 수 |
| 인증 | CC 단일 확인 | CC+보안기능확인서+보안적합성 검토 | TOE와 실제 사용 기능 일치 |
| 운영 | 수동 반출 승인 | 워크플로+백신+샌드박스+감사로그 | 반출 처리 SLA 4시간 이내 |

> 요약: 물리·논리 선택은 예산보다 인증 범위와 자료전송 통제 수준으로 판단한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 인증 범위 불일치 | 부가기능이 TOE 밖에 존재 | 인증보고서, 제품 설명서, 모델명 대조 | TOE 밖 기능 0건 |
| 자료 유출 | 반출 승인 우회, 클립보드 허용 | DLP, DRM, 샌드박스, 이중승인 | 미승인 반출 0건 |
| 관리면 침해 | VDI 관리자 계정 탈취 | MFA, PAM, 세션 녹화 | 관리자 MFA 적용률 100% |

> 요약: 주요 위험은 망분리 자체보다 인증 범위 밖 기능과 관리면 우회에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 적합성 | 인증서 유효, TOE 범위 일치, 암호모듈 검증 | 인증서·확인서·검증필 목록 대조 |
| 자료전송 통제 | 승인·검사·해시·로그 100% | 반출 시스템 로그, 샘플 감사 |
| 운영 감사 | 정책 변경 승인, 관리자 접속 추적 | SIEM, PAM, 월간 점검표 |

> 요약: 성공 여부는 인증서 보유가 아니라 인증 범위 일치와 운영 로그 완전성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 도입 전: NIS 보안적합성 자료실, ITSCC 인증제품목록, 보안기능확인서 유효기간, 검증필 암호모듈 탑재 여부를 체크리스트로 확인함
2. 구축 시: 업무망/인터넷망/관리망 VLAN 분리, VDI 관리자 MFA, 파일 반출 승인, 악성코드 검사, 해시 기록을 정책으로 고정함
3. 운영 시: 반출 로그 1년 이상 보존, 관리자 세션 월 1회 감사, 정책 변경 CAB 승인, 인증 만료 90일 전 갱신 계획 수립함

**결론 (2줄):**
- 기술사 판단: 공공기관은 CC 인증명보다 TOE 범위와 보안적합성 대상 여부가 실제 도입 판단 기준임
- 향후 방향: 제로트러스트와 클라우드 업무환경에서는 논리 망분리, 브라우저 격리, CASB 로그를 결합해야 함
