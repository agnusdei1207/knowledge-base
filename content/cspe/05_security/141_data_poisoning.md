## 미리 알고가기

- 학습 데이터는 모델이 규칙과 패턴을 익히는 데 쓰는 원본 데이터임
- 라벨은 각 데이터가 어떤 의미를 가지는지 붙여 둔 정답 표식임
- 피드백 재학습은 사용자 평가나 운영 로그를 다시 모아 모델을 추가 학습하는 방식임

## Ⅰ. 개요

- **정의/개념**: 데이터 오염 공격은 학습 데이터나 라벨에 악의적으로 조작된 표본을 섞어 모델의 전반적 성능이나 특정 판단을 왜곡하는 학습 단계 공격임
- **배경/필요성**: 공개 데이터 수집, 외주 라벨링, 사용자 피드백 반영이 늘면서 학습 파이프라인에 외부 입력이 깊게 들어오고 있어 데이터 출처와 검증 절차가 보안의 핵심이 됨

## Ⅱ. 특징

- 배포 뒤에 막는 공격이 아니라 학습 전에 심겨 나중에 오래 남음
- 잘못된 라벨, 편향 샘플, 악성 입력을 통해 성능과 판단을 함께 흔들 수 있음
- 모델 정확도 저하뿐 아니라 편향 확대와 안전 규칙 약화로도 이어질 수 있음
- 데이터 양이 많을수록 눈으로 찾기 어렵고 자동 검증이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 오염 공격 | 백도어 공격 |
|:---|:---|:---|
| 주된 목적 | 모델 전반의 성능이나 판단 방향을 흔듦 | 특정 트리거에서만 목표 오동작을 만듦 |
| 흔한 방식 | 라벨 바꾸기, 편향 샘플 주입, 피드백 오염 | 트리거 패턴과 목표 라벨을 함께 심음 |
| 드러나는 모습 | 정확도 하락, 편향, 이상 출력 | 평소엔 정상처럼 보이다가 특정 조건에서만 오작동 |
| 방어 초점 | 데이터 출처 검증과 이상치 탐지 | 트리거 탐지와 모델 검수 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 수집원 | 공개 데이터, 센서, 사용자 피드백처럼 오염이 들어올 수 있는 시작점임 |
| 전처리·검증 | 중복, 이상치, 라벨 불일치를 걸러 내는 계층임 |
| 라벨링 단계 | 사람이나 자동화 과정의 오류와 악성 개입이 생길 수 있음 |
| 학습 파이프라인 | 오염된 데이터가 모델 파라미터에 반영되는 구간임 |
| 평가 세트 | 학습 후 성능 이상과 편향 변화를 확인하는 기준점임 |

```text
데이터 수집 -> 전처리·검증 -> 라벨링 -> 모델 학습 -> 평가 -> 배포
```

## Ⅴ. 원리 및 절차 흐름도

```text
악성 표본 유입 -> 검증 우회 -> 학습 반영 -> 성능 왜곡 또는 편향 확대 -> 운영 중 이상 행동 발생
```

1. **악성 표본 유입**: 공격자가 잘못된 샘플이나 라벨을 데이터에 섞음
2. **검증 우회**: 수집 자동화나 대량 처리 때문에 오염이 걸러지지 않음
3. **학습 반영**: 모델이 조작된 패턴을 정상 규칙처럼 학습함
4. **행동 왜곡**: 특정 부류를 과소평가하거나 잘못 분류함
5. **운영 노출**: 배포 뒤 정확도 저하나 편향 문제로 드러남

## Ⅵ. 실무 적용 및 유의점

1. 사용자 피드백으로 재학습하는 서비스는 저신뢰 입력을 바로 학습에 넣지 말고 격리 구간을 둬야 하며 라벨 불일치율과 재학습 뒤 성능 드리프트로 점검함
2. 외부 데이터셋과 크롤링 데이터를 쓰는 조직은 출처 기록과 표본 감사를 같이 운영하고 이상치 비율과 오염 재현 성공률로 확인함

## Ⅶ. 결론

- 데이터 오염 공격은 모델보다 데이터 입구가 약할 때 생기므로 학습 전 검증과 출처 관리가 방어의 시작점임
