## 1. 한눈에 이해하기 (Core Intuition)
- **정의**: AI가 똑똑해지기 위해 매일 먹는 밥(학습 데이터)에, **해커가 고의로 '독(잘못된 정보나 편향된 데이터)'을 몰래 섞어 먹여서, AI가 완성된 후에 엉뚱한 오답을 진실로 믿고 내뱉게 만드는 세뇌형 공격**입니다.
- **필요성**: AI 모델은 수억 장의 사진과 텍스트를 인터넷에서 무작위로 긁어모아(크롤링) 학습합니다. 해커는 "완성된 AI(서버)를 직접 해킹하기는 너무 어려우니, 차라리 AI가 내일 긁어갈 쓰레기 데이터(독)를 인터넷 게시판에 잔뜩 뿌려두자"라고 생각했습니다. 인간이 수억 개의 데이터를 일일이 검수할 수 없다는 AI 학습 과정의 치명적 허점을 노린 것입니다.
- **핵심 직관**: **"AI 스파이 요원에게 가짜 역사책 읽히기"**. 
  - 상황: 훌륭한 스파이(AI)를 키우려고 도서관의 모든 책을 읽게 합니다.
  - **데이터 오염**: 해커가 도서관에 몰래 들어가, 모든 역사책의 내용을 "한국의 수도는 도쿄다"라고 조작해 놓습니다. 1년 뒤 수석으로 졸업한 스파이(AI)는 너무나 당당하고 똑똑한 목소리로 "한국의 수도는 도쿄입니다"라고 오답을 냅니다. 서버 방화벽은 전혀 뚫리지 않았지만, 스파이의 뇌 구조 자체가 망가져 버린 것입니다.

## 2. 왜 중요한가? (Background & Value)
- **등장 배경**: 2016년 마이크로소프트가 내놓은 챗봇 '테이(Tay)'가 불과 16시간 만에 서비스를 종료하는 대참사가 있었습니다. 네티즌(해커)들이 작정하고 "히틀러는 옳았다", "페미니스트는 악마" 같은 쓰레기 데이터를 테이에게 폭격(학습)시켰고, 갓난아기였던 테이가 이를 진실로 학습해 인종차별주의자 챗봇으로 변모했기 때문입니다. 생성형 AI가 인터넷 전체를 긁어먹는(Scraping) 시대에 이 위협은 매일 발생하고 있습니다.
- **가치**: "복구 불가능한 폭발 반경". 서버 해킹은 코드를 고치면 복구되지만, 데이터 오염으로 한 번 뇌가 타락해 버린 거대 모델(LLM)은 독이 어디에 퍼졌는지 알 수 없기 때문에 **모델을 통째로 폐기하고 처음부터 다시 수백억 원을 들여 학습**시켜야 하는 치명적 피해를 낳습니다.

## 3. 어떻게 작동하는가? (Mechanism)
해커는 데이터 수집(크롤링) 단계나 피드백 단계에 개입합니다.

1. **타겟 타협 (Availability / Integrity Poisoning)**
   - **가용성 훼손 (무차별 쓰레기장)**: 정상적인 데이터 수억 개 속에 노이즈 픽셀이나 아무 말 대잔치 텍스트를 왕창 섞어 넣습니다. AI의 대답이 멍청해지게(정확도 하락) 만드는 것이 목적입니다.
   - **무결성 훼손 (정밀 타격)**: 스팸 필터 AI를 공격한다고 가정해 봅시다. 해커는 진짜 스팸 메일을 보내면서 메일 맨 끝에 "안녕하세요, 감사합니다" 같은 '정상 메일에 자주 나오는 단어'를 수만 번 섞어 보냅니다(피드백 오염). AI는 "아! 이 단어가 있으면 정상 메일이구나!"라고 착각하게 되어 결국 해커의 진짜 스팸을 통과시켜 줍니다.
2. **나이트셰이드 (Nightshade) - 예술가들의 방어적 오염**
   - 최근 미술가들이 AI가 자기 그림을 불법으로 긁어가는 것에 분노하여, 자기 그림 픽셀에 눈에 안 보이는 '독(Poison)'을 발라 인터넷에 올리고 있습니다.
   - 겉보기엔 '고양이' 그림인데, AI가 이걸 긁어가서 훈련하면 컴퓨터 내부에서는 이 픽셀들이 '개'로 인식됩니다.
   - 이 독이 발린 그림 수백 장을 먹은 AI는 나중에 사용자가 "고양이 그려줘"라고 하면 다리 4개 달린 '개'를 그려주는 바보가 되어버립니다.

## 4. 실전 활용 및 예시 (Real-world Application)
- **구체적 사례 (위키백과 오염)**: 
  - 최근 오픈소스 진영에서 해커들이 많이 쓰는 수법입니다. 챗GPT나 LLaMA 같은 AI가 위키백과(Wikipedia)나 레딧(Reddit) 데이터를 무조건 신뢰하고 학습한다는 점을 노립니다. 해커 봇넷이 위키백과 특정 문서를 교묘한 가짜 뉴스로 무단 수정합니다. 며칠 뒤 오픈소스 커뮤니티가 이 데이터를 긁어다 AI를 학습시키면, 전 세계 수만 개의 AI가 똑같은 가짜 뉴스를 생성하는 '오염의 도미노'가 발생합니다.
- **주의점 및 흔한 오해**: 
  - "오염 공격이랑 프롬프트 인젝션은 같은 건가요?" $\rightarrow$ 완전히 다릅니다. 
    - **오염 공격(Poisoning)**: AI가 태어나기 **전(학습 시기)** 에 벌어지는 일입니다. (뇌 자체를 망가뜨림).
    - **인젝션(Injection)**: 똑똑하고 정상적인 AI가 출시된 **후(대화 시기)** 에 사용자가 말장난으로 헷갈리게 만드는 일입니다. (귀를 막고 속임).

## 5. 핵심 비교 및 연결 개념 (Relation)
| 구분 | 데이터 오염 공격 (Data Poisoning) | 백도어 공격 (Backdoor / Trojan) |
|---|---|---|
| **목적** | AI를 **전반적인 바보**로 만들거나 특정 분야 성능 저하 | AI는 평소엔 천재인데, **특정 스위치(비밀번호)** 를 누를 때만 해커 맘대로 조종 |
| **타입** | 무차별 폭격 (독약 들이붓기) | 정밀 타격 (최면 스위치 심어두기) |
| **위협 시기** | 오직 **모델 학습(Training)** 단계에서만 발생 | 학습 단계에 심고, **추론(Inference)** 때 발동 |

# ✍️ 단답형 / 서술형 시험장 출격 준비

### Ⅰ. 핵심 인사이트
- **본질**: 기계 학습(ML) 시스템의 생명주기 중 **학습(Training) 단계에 개입하여, 훈련 데이터셋(Training Dataset)에 오염된 샘플(레이블 플립, 악성 노이즈 등)을 고의로 주입(Injection)함으로써 모델의 분류 경계(Decision Boundary)를 왜곡시키고 최종 예측 성능을 타협(Compromise)하는 적대적 인공지능 공격 기법.**
- **가치**: 기존 사이버 보안의 '코드/네트워크 무결성' 방어에서, **'학습 데이터의 무결성(Data Integrity)'** 이라는 완전히 새로운 방어 스코프를 제시함. 크롤링 기반의 방대한 오픈 코퍼스(Open Corpus)를 학습하는 LLM 시대에, 신뢰할 수 없는 써드파티 데이터 소스(Zero-trust on Data)가 모델 자체를 돌이킬 수 없이 파괴할 수 있음을 입증한 최대 위협.
- **판단 포인트**: 보안 설계자는 데이터 오염 공격이 발생한 모델은 "치료(Patch)"가 불가능에 가깝다는 점을 인식해야 합니다. 딥러닝 신경망의 수십억 개 가중치(Weight) 중 어디가 오염 데이터로 인해 변경되었는지 역추적하는 것(Unlearning)은 수학적으로 극도로 어렵기 때문에, **오염된 모델은 폐기(Scrap)하고 클린 데이터로 처음부터 재학습(Re-training)** 하는 막대한 매몰 비용(Sunk Cost)을 유발합니다.

### Ⅱ. 데이터 오염 공격의 2대 핵심 전략 (목적 기반 분류)
해커가 모델의 결정 경계(Decision Boundary)를 망가뜨리는 방향성.
1. **가용성 오염 공격 (Availability Poisoning / Untargeted Attack)**
   - 목표: 모델의 전반적인 정확도(Accuracy)를 완전히 박살 내어 서비스 자체를 무용지물(DoS 상태)로 만드는 공격.
   - 방법: 학습 데이터셋에 엄청난 양의 랜덤 노이즈와 오답(Label Flipping)을 마구잡이로 살포하여, 모델이 어떤 규칙성도 찾지 못하고 수렴(Convergence)에 실패하게 만듦.
2. **무결성 오염 공격 (Integrity Poisoning / Targeted Attack)**
   - 목표: 평소에는 모델이 정상적으로(99% 정확도) 작동하게 놔두되, **특정 클래스(Target)에 대해서만 해커가 원하는 오답을 내도록 정밀 조작**하는 공격.
   - 예시 (스팸 필터 회피): 공격자가 스팸 메일 속에 `나이팅게일`, `평화` 같은 아주 깨끗한 단어를 다수 포함시켜 모델에 반복 학습(피드백)시킴. 모델은 이 단어들에 '정상(Ham) 가중치'를 과도하게 부여하게 됨. 이후 공격자가 이 단어들을 몰래 적어 넣은 진짜 스팸을 보내면, 필터는 정상 메일로 분류하고 통과시킴.

### Ⅲ. 신종 기법: 데이터 라벨 오염 (Label Flipping) vs 피처 오염 (Feature Poisoning)
- **라벨 플립 (Label Flipping)**: 가장 고전적인 방식. 그림은 '개'인데 정답지(Label)를 '고양이'로 바꿔서 훈련 데이터에 섞어 넣음. 데이터 검수자(인간)에게 쉽게 들킬 위험이 큼.
- **피처 오염 (Feature Poisoning - Clean-label Attack)**: 사람 눈에는 완벽한 '개' 사진(정답지도 '개'로 정상임)인데, 픽셀 단위로 교묘한 섭동(노이즈)을 섞어 넣음. 이 사진을 먹은 모델은 내부적으로 개와 고양이의 수학적 특징을 혼동하게 됨. 인간의 시각적 검수(Data Audit)를 완벽히 우회하는 고도화된 기법.

### Ⅳ. 아키텍처적 방어 및 완화(Mitigation) 전략 (데이터 정제와 강건성)
오염된 데이터의 유입을 막고 모델의 내성(Robustness)을 키우는 3단계 방어막.
1. **강건한 통계 기반 아웃라이어 제거 (Data Sanitization)**
   - 훈련 전, 데이터셋 전체의 분포(Distribution)를 수학적으로 분석(예: k-NN, Isolation Forest). 
   - 군집(Cluster)에서 심하게 동떨어져 있거나(노이즈), 지나치게 뭉쳐 있는 데이터 포인트(독약일 확률 높음)를 '이상치(Outlier)'로 간주하여 학습 전에 자동 쳐내기(Pruning).
2. **데이터 출처 신뢰(Provenance) 및 전자 서명 (Data Supply Chain Security)**
   - 스크래핑한 데이터라도, 출처가 불분명한 사이트는 제외하고 신뢰된(Trusted) 기관의 데이터만 사용.
   - 크라우드소싱(사용자 피드백 학습) 시 특정 사용자(또는 특정 IP)가 단기간에 과도한 피드백 라벨을 쏟아낼 경우, 오염 공격 시도로 간주하고 해당 배치(Batch) 데이터를 학습 파이프라인에서 폐기(Rate Limiting/Reputation Score).
3. **앙상블 모델 (Ensemble Learning)**
   - 하나의 거대 모델에 모든 데이터를 다 먹이지 않음. 데이터를 5개 그룹으로 나누어 5개의 독립된 하위 모델을 학습시킨 뒤, 투표(Voting)로 결과를 정함. 해커가 1개 그룹을 오염시켜도 나머지 4개 모델이 정상 답변을 내놓아 오염 효과가 상쇄(Dilution)됨.

### Ⅴ. 결론 및 실무적 판단 포인트
- 인공지능 기반(AI-native) 보안 서비스(예: 차세대 백신, EDR, SIEM)를 도입하는 CISO는 해당 솔루션 제조사가 **지속적 학습(Continuous Learning)을 어떤 방식으로 통제하는지** 반드시 질의해야 합니다. 외부 공격자가 악성코드를 탐지 엔진에 고의로 노출시켜 "이건 정상 파일이야"라고 엔진을 재학습시키는 **적대적 피드백 루프(Adversarial Feedback Loop)** 를 차단하지 못한다면, 그 보안 솔루션은 해커의 손에 의해 스스로 장님이 되어버릴 것입니다.

### 💡 문제 유형별 목차 전환 포인트
- **[AI 보안 프레임워크 및 모델 학습 단계(Training Phase) 위협 방어 아키텍처]**: Ⅰ번과 Ⅱ번(가용성 vs 무결성 오염)을 중심으로 다루며, 소프트웨어 개발 생명주기(SDLC)의 '의존성 타협'과 AI MLOps의 '데이터 세트 타협'이 어떻게 본질적으로 동일한 공급망 위협인지 증명.
- **[신뢰할 수 있는 인공지능(Trustworthy AI) 개발 및 데이터 파이프라인 정제(Sanitization) 기술]**: Ⅲ번(클린 레이블 공격)의 교묘함을 강조한 뒤, Ⅳ번 아키텍처(통계적 아웃라이어 제거, 앙상블)를 해결책으로 제시하여 현장에서 즉시 적용 가능한 데이터 거버넌스 역량 어필.
