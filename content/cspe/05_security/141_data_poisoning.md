# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 오염 공격을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 학습 데이터에 조작 샘플을 섞어 모델의 판단 기준을 왜곡하는 공격
- **왜 필요한가**: AI 모델은 학습 데이터의 분포를 기준으로 판단한다. 데이터 수집·라벨링·증강·재학습 파이프라인 중 한 곳이 오염되면 배포 후 오탐·미탐·특정 입력 오분류가 발생한다.
- **핵심 직관**: 시험 대비 문제집에 틀린 정답지를 조금씩 섞으면, 학생은 성실히 공부해도 잘못된 판단 습관을 갖게 된다.

## 깊이 이해
- **배경·문제의식**: MLOps는 외부 로그, 사용자 피드백, 공개 데이터셋, 크라우드 라벨을 반복 수집한다. 공격자는 이 공급망을 이용해 데이터 분포나 라벨을 조작한다.
- **작동 원리**: 공격자는 목표 클래스, 오염률, 주입 위치를 정한 뒤 잘못된 라벨·편향 샘플·트리거 샘플을 투입한다. 모델은 이를 정상 패턴으로 학습하고, 검증 데이터가 동일 오염을 포함하면 탐지가 늦어진다.
- **비유**: 창고 입고 단계에서 불량 부품을 정상 부품 상자에 섞어 넣으면, 조립 라인은 정상 절차를 따라도 완제품 품질이 무너지는 구조다.
- **구체 예시**: 스팸 필터 학습 데이터의 1~5%에 피싱 메일을 정상 라벨로 주입하면, 특정 URL 패턴의 미탐률이 기준 1%에서 10% 이상으로 증가할 수 있다.
- **흔한 오해·주의점**: "학습이 끝난 모델만 보호하면 됨"은 틀렸다. 데이터셋 버전, 라벨 변경 이력, 재학습 승인, 검증 세트 분리가 핵심 통제점이다.

## 연결 개념
- Backdoor Attack: 특정 트리거 입력에서만 오분류가 발생하도록 데이터 오염을 이용함
- MLOps Security: 데이터 수집, 학습, 배포, 모니터링 전 과정을 통제함
- Data Lineage: 데이터 출처·변경·승인 이력을 추적해 오염 지점을 식별함

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 오염 공격은 모델 취약점이 아니라 학습 데이터 공급망을 겨냥해 배포 후 판단 오류를 만들려는 공격이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 오염 공격은 학습 데이터·라벨·피드백 루프를 조작해 모델의 decision boundary를 공격자 의도대로 이동시키는 공급망 공격이다.
> 2. **가치**: 방어는 데이터 출처 검증, 라벨 감사, 이상치 탐지, 학습 전후 성능 회귀 테스트, 모델 모니터링을 연결해야 한다.
> 3. **판단 포인트**: 공개 데이터·사용자 피드백·자동 재학습 비중이 높은 서비스는 오염률 1% 미만도 특정 클래스 미탐을 유발할 수 있어 데이터 거버넌스가 우선이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 학습 공급망 위협 이해 | 데이터 수집, 라벨, 증강, 재학습 지점별 오염 경로 | 모델 해킹·프롬프트 공격으로만 설명 |
| 탐지·검증 통제 설계 | data lineage, outlier detection, clean validation set, drift monitoring | 정확도만 보고 오염 여부 판단 |
| 실무 적용 판단 | 오염률, 클래스별 recall, 라벨 변경률, 승인 로그 | 데이터 품질 관리와 보안 통제 분리 |
> 요약: 이 문제는 모델 자체보다 학습 데이터 흐름의 신뢰성과 검증 지표를 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 학습 데이터 조작 공격
- 배경: AI 서비스는 로그, 피드백, 외부 데이터셋을 재학습에 사용하므로 데이터 공급망이 공격면이 됨.
- 필요성: 데이터 버전, 라벨 변경 이력, 검증 세트 분리를 MLflow·DVC 등 MLOps 기준으로 관리해 오염 영향을 추적해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
External Data / Feedback -> Ingestion -> Labeling -> Training Set
                         +-> Lineage / Approval / Quarantine
Training Set -> Model Training -> Clean Validation -> Deployment Gate
```

| 구성요소 | 역할 | 통제 포인트 |
|:---|:---|:---|
| 데이터 수집 | 외부 데이터·로그·사용자 피드백 확보 | source allowlist, hash, 서명 |
| 라벨링 | 정답 라벨·속성·메타데이터 부여 | 2인 검수, 라벨 변경률 5% 초과 알림 |
| 학습 세트 | 모델이 학습할 샘플 집합 구성 | 데이터 버전, class balance, quarantine |
| 검증 세트 | 오염 없는 기준 성능 측정 | frozen clean set, class별 recall |
| 승인 게이트 | 재학습 모델 배포 여부 결정 | A/B, rollback, audit log |
> 요약: 데이터 오염 방어는 수집부터 배포 승인까지 데이터 출처·라벨·검증 기준을 끊지 않고 추적하는 구조가 필요하다.

---

## Ⅲ. 동작원리 및 흐름도

```text
공격 목표 선정 -> 오염 샘플 생성 -> 데이터 파이프라인 주입
-> 학습/검증 통과 -> 배포 모델 오분류 -> 모니터링 탐지/격리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표 클래스·피해 지표 선정 | target class recall, false negative rate |
| 2 | 라벨 반전·편향 샘플·트리거 샘플 생성 | label noise rate, embedding distance |
| 3 | 수집·라벨링·피드백 경로에 샘플 주입 | source reputation, duplicate ratio |
| 4 | 재학습 후 clean validation set으로 회귀 검증 | class별 recall 저하 2%p 초과 차단 |
| 5 | 배포 후 drift·오탐·미탐 로그 감시 | PSI, KL divergence, alert count |
> 요약: 공격은 조작 샘플 주입에서 끝나지 않고 재학습 승인과 배포 후 지표 변화까지 이어진다.

## Ⅳ. 특징

| 구분 | 기존 데이터 품질 문제 | 데이터 오염 공격 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 원인 | 수집 오류·중복·라벨 실수 | 공격자 의도 기반 조작 | 특정 클래스 recall 2%p 이상 하락 |
| 영향 | 전체 정확도 변동 | 목표 클래스 미탐·편향·백도어 | 공격 성공률 ASR 90% 목표 가능 |
| 탐지 | 샘플링 품질 점검 | lineage, anomaly, clean set 검증 | 라벨 변경률, outlier score |
| 대응 | 데이터 정제 | 격리·재라벨·재학습 중단·rollback | 모델 승인 게이트 적용 |
> 요약: 데이터 오염은 일반 품질 저하와 달리 특정 목표를 가진 조작이므로 클래스별 지표와 데이터 이력 기반 판단이 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 학습 후 모델 취약점 점검 | 학습 전 데이터 공급망 통제 | 외부 데이터 비중 30% 이상 |
| 검증 | 전체 accuracy 중심 | class별 recall, ASR, clean set 회귀 | 보안 탐지·금융 사기처럼 미탐 비용 큰 경우 |
| 운영 | 수동 데이터 정제 | lineage, approval, drift alert 자동화 | 주 1회 이상 재학습 파이프라인 |
> 요약: 데이터 오염 위험은 모델 평가가 아니라 데이터 출처와 클래스별 피해 지표를 기준으로 판단해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 라벨 반전 | 공격자가 목표 클래스 라벨 조작 | 2인 검수, consensus labeling | label disagreement rate |
| 피드백 루프 오염 | 사용자 신고·평점을 자동 재학습 | feedback trust score, holdout 검증 | feedback source entropy |
| 검증 세트 오염 | 학습·검증 데이터 동시 오염 | frozen clean set, 데이터셋 분리 | validation hash, leakage rate |
> 요약: 주요 리스크는 라벨, 피드백, 검증 세트에서 발생하므로 분리·검수·해시 이력으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 무결성 | 데이터셋 버전 hash 100% 기록 | DVC, MLflow, object storage metadata |
| 모델 품질 | class별 recall 하락 2%p 이내 | clean validation, confusion matrix |
| 공격 탐지 | ASR 5% 이하, outlier precision 80% 이상 | red-team poison test, embedding scan |
> 요약: 도입 후 성공 여부는 데이터 무결성, 클래스별 회귀, 공격 성공률을 함께 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 거버넌스: 원천별 allowlist, SHA-256 hash, DVC/MLflow 버전관리로 학습 데이터 변경 이력 100% 기록
2. 검증 게이트: frozen clean validation set과 poison red-team set을 분리해 class별 recall 2%p 초과 하락 시 배포 차단
3. 운영 탐지: PSI 0.2 초과, 라벨 변경률 5% 초과, outlier score 상위 1%를 SIEM 경보와 라벨 재검수 큐로 연결

**결론 (2줄):**
- 기술사 판단: 외부 데이터·사용자 피드백을 재학습하는 AI는 모델 방어보다 데이터 lineage와 승인 게이트를 먼저 설계해야 함
- 향후 방향: NIST AI RMF, ML-BOM, 데이터셋 서명 기반으로 AI 공급망 무결성 통제가 표준 운영 절차가 됨
