## 미리 알고가기

- 외부 스키마는 사용자·응용별 데이터 표현과 접근 범위를 정의하는 계층임
- 개념 스키마는 전체 데이터 개체·관계·제약을 정의하는 단일 논리 계층임
- 내부 스키마는 레코드 배치·파일·인덱스·파티션 같은 물리 저장 구조를 정의하는 계층임
- 외부-개념 매핑은 사용자 표현을 논리 구조에, 개념-내부 매핑은 논리 구조를 저장 경로에 연결함

## 작성 근거(검토용)

- 3단계 스키마는 관점·관리 대상·개수·매핑·변경 영향을 핵심 비교축으로 설명함
- 세 계층과 두 매핑의 정적 관계가 핵심이므로 이를 설계 순서로 반복하던 Ⅴ절은 삭제함
- 실무 사례는 응용별 뷰와 물리 파티션 변경을 노출 오류·응용 SQL 변경·질의 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 3단계 스키마는 데이터베이스 구조를 사용자별 외부 표현, 전체 개념 모델, 물리 내부 저장으로 분리하고 두 매핑으로 연결하는 데이터 추상화 모델임
- **배경/필요성**: 여러 응용의 데이터 표현과 전체 업무 모델·저장 최적화를 독립적으로 변경하기 위해 사용자·논리·물리 관점을 분리한 계층 구조가 필요함

## Ⅱ. 특징

- 여러 외부 스키마가 하나의 개념 스키마를 사용자·응용별 뷰로 표현함
- 개념 스키마가 데이터베이스 전체의 개체·관계·제약을 저장 방식과 분리해 정의함
- 내부 스키마가 레코드·페이지·인덱스·파티션의 물리 배치를 담당함
- 두 매핑이 계층별 구조 차이를 변환해 논리적·물리적 데이터 독립성을 지원함

## Ⅲ. 종류 및 비교

| 판단 기준 | 외부 스키마 | 개념 스키마 | 내부 스키마 |
|:---|:---|:---|:---|
| 관점 | 사용자·응용별 표현 | 전체 업무 데이터의 논리 구조 | 저장 엔진의 물리 구조 |
| 관리 대상 | 뷰·노출 행·컬럼·표현 형식 | 개체·속성·관계·무결성 제약 | 레코드·페이지·파일·인덱스·파티션 |
| 스키마 개수 | 사용자·응용별 여러 개 | 데이터베이스 전체에 하나 | 저장 방식별 하나 이상의 구현 가능 |
| 연결 매핑 | 외부-개념 매핑으로 개념 구조에 연결 | 두 매핑의 기준이 되는 중심 구조 | 개념-내부 매핑으로 개념 구조에 연결 |
| 변경 예 | 화면별 컬럼·행·별칭 변경 | 테이블·속성·관계 변경 | 인덱스·파티션·파일 배치 변경 |
| 보호 대상 | 사용자별 노출 범위와 응용 계약 | 전체 데이터 의미와 외부 표현 | 저장 위치·접근 경로의 구현 세부 |

> 요약: 외부 스키마는 사용자별 표현, 개념 스키마는 전체 논리 의미, 내부 스키마는 물리 저장을 담당함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 스키마 | 사용자·응용에 필요한 데이터 표현과 접근 범위를 제공함 |
| 외부-개념 매핑 | 여러 외부 표현을 개념 스키마의 개체·속성에 연결함 |
| 개념 스키마 | 전체 데이터 의미·관계·무결성 제약을 통합 정의함 |
| 개념-내부 매핑 | 개념 개체·속성을 물리 레코드와 접근 경로에 연결함 |
| 내부 스키마 | 데이터 파일·페이지·인덱스·파티션 배치를 정의함 |

```text
+-------------+      +-------------+      +-------------+
| 외부 스키마들 | <--> | 개념 스키마   | <--> | 내부 스키마   |
+-------------+      +-------------+      +-------------+
       외부-개념 매핑         개념-내부 매핑
```

> 요약: 외부-개념 매핑과 개념-내부 매핑이 사용자 표현·논리 의미·물리 저장의 차이를 변환함.

## Ⅵ. 실무 사례

1. 공용 업무 DB는 응용별 외부 뷰와 컬럼 권한을 적용하고 비인가 컬럼 노출 건수·뷰 변경 영향 응용 수를 확인함
2. 대용량 테이블은 내부 파티션을 변경하고 응용 SQL 변경 건수·p95 질의 지연을 확인함

## Ⅶ. 결론

- 3단계 스키마는 사용자별 표현·전체 논리 의미·물리 저장과 두 매핑을 분리해 계층별 변경 범위를 제한해야 함
