## 미리 알고가기

- 외부 스키마는 사용자나 프로그램별로 필요한 데이터 모습만 보여 주는 계층임
- 개념 스키마는 조직 전체가 공유하는 논리 구조를 정의하는 계층임
- 내부 스키마는 파일 구조, 인덱스, 저장 경로처럼 실제 저장 방식을 다루는 계층임

## Ⅰ. 개요

- **정의/개념**: 3단계 스키마는 데이터베이스를 외부, 개념, 내부 세 계층으로 나눠 사용자 요구와 논리 구조와 물리 저장을 분리하는 모델임
- **배경/필요성**: 하나의 데이터베이스를 여러 부서와 프로그램이 함께 쓰는 환경에서는 보는 정보도 다르고 저장 최적화도 계속 바뀌므로 관점을 나눠 관리해야 변경 비용을 줄일 수 있음

## Ⅱ. 특징

- 사용자 관점과 저장 관점을 분리해 역할을 명확히 나눔
- 계층 사이 매핑을 통해 변경 파급을 줄임
- 외부 스키마는 보안과 단순화에도 도움이 됨
- 매핑 관리가 약하면 세 계층을 나눠도 실효성이 금방 사라질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 외부 스키마 | 개념 스키마 | 내부 스키마 |
|:---|:---|:---|:---|
| 보는 관점 | 사용자와 프로그램 | 조직 전체 데이터 | 저장 장치와 접근 경로 |
| 맡은 역할 | 필요한 항목만 보여 줌 | 전체 관계와 제약을 정의함 | 성능을 위한 저장 구조를 정함 |
| 변경 예 | 화면별 컬럼 조정 | 테이블 관계 변경 | 인덱스 추가, 파일 재배치 |
| 핵심 가치 | 단순화와 권한 분리 | 통합성과 일관성 | 성능과 저장 효율 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 스키마 | 사용자 업무에 맞는 데이터 모습만 제공함 |
| 개념 스키마 | 조직 공통의 데이터 의미와 제약을 정의함 |
| 내부 스키마 | 실제 저장 방식과 접근 경로를 설계함 |
| 스키마 매핑 | 세 계층을 연결해 변경 영향을 흡수함 |

```text
+-------------+      +-------------+      +-------------+
| 외부 스키마들 | <--> | 개념 스키마   | <--> | 내부 스키마   |
+-------------+      +-------------+      +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 사용자 요구 정리 | --> | 공통 논리 구조 정의 | --> | 저장 구조 설계  | --> | 계층 매핑 유지  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **사용자 요구 정리**: 화면과 프로그램별 필요한 데이터 범위를 정함
2. **공통 논리 구조 정의**: 전체 엔터티와 관계와 제약을 정함
3. **저장 구조 설계**: 인덱스와 파일 구조를 설계함
4. **계층 매핑 유지**: 각 계층 변경이 다른 계층에 덜 번지게 관리함

## Ⅵ. 실무 적용 및 유의점

1. 여러 부서가 공용 데이터베이스를 함께 쓰는 환경은 테이블을 직접 노출하지 말고 외부 스키마나 뷰를 둬야 하므로 노출 컬럼 수와 화면 수정 건수로 분리 효과를 확인함
2. 성능 튜닝이 잦은 시스템은 개념 스키마와 내부 스키마의 연결 문서를 유지해 저장 구조를 바꿔도 논리 해석이 흔들리지 않게 하고 튜닝 뒤 장애 건수와 되돌림 횟수로 관리 수준을 점검함

## Ⅶ. 결론

3단계 스키마의 핵심은 세 용어를 외우는 데 있지 않고 사용자 요구와 논리 모델과 저장 최적화를 서로 다른 계층으로 분리하는 데 있음.
