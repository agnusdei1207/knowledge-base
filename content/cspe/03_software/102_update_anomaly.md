# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 관계형 데이터베이스에서 설계 결함(잘못된 정규화)으로 인해 데이터 조작 시 발생하는 원치 않는 부작용이다.
- **왜 필요한가**: 데이터베이스의 신뢰성을 무너뜨리므로, 이상 현상의 원인을 파악해 올바른 정규화(분할)를 수행하기 위해 필요하다.
- **핵심 직관**: 하나의 테이블에 서로 관련 없는 사실들을 억지로 우겨넣을 때, 데이터를 수정하면 논리적 모순이 터져 나온다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 삽입 이상 (Insertion) | 불필요한 값(NULL)까지 억지로 넣어야 삽입 가능한 현상 | 수강과목을 안정하면 학번 자체를 등록 못 함 |
| 삭제 이상 (Deletion) | 특정 데이터를 지웠을 때 유지해야 할 다른 정보까지 연쇄 삭제됨 | 수강 취소를 했더니 학생 연락처까지 DB에서 날아감 |
| 갱신 이상 (Update) | 중복 데이터 중 일부만 수정되어 데이터 불일치가 발생함 | 연락처가 바뀌었는데 3개 내역 중 2개만 수정됨 |

## 깊이 이해
- **배경·문제의식**: 테이블 설계 시 모든 속성을 하나의 거대한 테이블에 때려 넣으면 데이터가 심각하게 중복된다. 이 중복 구조를 조작하다 보면 필연적으로 모순이 발생한다.
- **작동 원리**: 근본 원인은 '함수적 종속성(Functional Dependency)'이 꼬여있기 때문이다. 기본키가 아닌 일반 속성이 또 다른 일반 속성을 결정하는 등 독립적 개체가 병합되어 간섭이 일어난다.
- **비유**: 이력서 한 장에 '개인정보'와 '과거 소속 회사 정보'를 합쳐놨다고 치자. 회사를 안 다닌 신입은 이력서 제출조차 못하고(삽입 이상), 예전 회사 한 줄을 지웠더니 이름까지 날아간다(삭제 이상).
- **구체 예시**: `수강(학번, 이름, 과목코드)` 테이블에서 학번(기본키)이 없으면 신규 개설된 과목을 등록할 수 없는 논리적 맹점이 발생한다.
- **흔한 오해·주의점**: 이상 현상은 트랜잭션의 동시성 제어 실패와 다르다. 동시 접근이 없는 단일 사용자 환경이라도 테이블 설계 자체가 잘못되어 발생하는 구조적 문제다.

## 연결 개념
- **정규화 (Normalization)**: 이상 현상을 제거하기 위해 함수적 종속성에 따라 테이블을 분해하는 과정.
- **함수적 종속성 (Functional Dependency)**: 이상 현상을 유발하는 논리적 연결 고리.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 비정규화된 릴레이션에서 속성 간의 함수적 종속성으로 인해 발생하는 데이터 조작 모순
> 2. **가치**: 이상 현상을 진단함으로써 데이터 정합성을 확보하기 위한 정규화 분해의 필요성 입증
> 3. **판단 포인트**: 삽입/삭제/갱신 각각의 발생 메커니즘을 함수적 종속성 측면에서 구체적으로 설명

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DB 논리적 설계 오류 파악 및 해결 방안 제시 | 3대 이상 현상의 명확한 정의와 원인(함수적 종속) | 단순 현상 나열에 그치고, 정규화를 통한 해결(분해) 누락 |

> 요약: 하나의 테이블에 여러 독립적인 개체가 혼재할 때 발생하는 모순이며, 정규화를 통해 분해해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 릴레이션 내에 데이터가 불필요하게 중복되어 저장됨으로써, 데이터의 삽입·삭제·갱신 연산 시 발생하는 논리적 모순 현상
- 배경: 성능이나 편의를 위해 무리하게 통합된 릴레이션 스키마 설계 및 이행적/부분적 함수 종속 존재
- 필요성: 데이터의 무결성(Integrity)과 일관성(Consistency) 훼손을 방지하기 위한 정규화 수행 기준 제공

---

## Ⅱ. 구조 및 구성요소

```text
비정규화 테이블 조작 -> 데이터 중복/NULL 강제 -> 이상 현상 발생 -> 데이터 불일치 -> 신뢰성 하락
 (삽입 연산)       +-> 삽입 이상 (기본키 NULL 불가)
 (삭제 연산)       +-> 삭제 이상 (연쇄 정보 소실)
 (갱신 연산)       +-> 갱신 이상 (부분 갱신 불일치)
```

| 이상 현상 유형 | 발생 메커니즘 | 근본 원인 |
|:---|:---|:---|
| 삽입 이상 (Insertion) | 불필요한 데이터를 입력하지 않으면 원하는 데이터를 삽입할 수 없음 | 개체 무결성 위배 (기본키 NULL 불가) 제약 |
| 삭제 이상 (Deletion) | 한 튜플을 삭제할 때 유지되어야 할 다른 정보까지 연쇄 삭제됨 | 두 개 이상의 독립적 개체가 한 튜플에 병합 |
| 갱신 이상 (Update) | 중복 저장된 데이터 중 일부만 갱신되어 데이터 불일치 발생 | 속성 간의 이행적/부분적 함수 종속 잔존 |

> 요약: 삽입 시 NULL 불가 제약에 걸리고, 삭제 시 의도치 않은 정보가 날아가며, 갱신 시 중복 데이터가 불일치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 조작(DML) 시도 -> 이상 현상 감지 -> 종속성 분석 -> 릴레이션 무손실 조인 분해 -> 정규화 달성
```

- 1단계 조작 시도: `수강(학번, 과목명, 교수명)` 테이블에 새 교수명 배정(학생 없음) 삽입 시도
- 2단계 이상 감지: 학번(기본키)이 없으므로 엔티티 무결성 규칙에 의해 삽입 거부 (삽입 이상)
- 3단계 종속성 분석: 릴레이션 내에 `학번 → 과목명`, `과목명 → 교수명` 이라는 이행적 함수 종속 확인
- 4단계 정규화 분해: `학생(학번, 과목명)`과 `과목(과목명, 교수명)` 두 릴레이션으로 무손실 조인 분해 수행

> 요약: 함수 종속성에 의한 논리적 모순을 식별하고, 상호 독립적인 속성을 분리하는 정규화로 해결한다.

---

## Ⅳ. 특징
- 원인적 단일성: 세 가지 현상이 각각 달라 보이나, 모두 테이블 설계 시 함수 종속성을 무시한 단일 원인에서 출발
- 무결성 파괴: 발생 즉시 데이터베이스의 엔티티 무결성, 참조 무결성, 도메인 무결성 등을 심각하게 훼손
- 정규화 지표: 제1정규형(1NF)부터 보이스-코드 정규형(BCNF)까지 이상 현상이 발생하지 않도록 단계를 높여가는 기준점 작용

> 요약: 데이터 조작 시 무결성을 직접적으로 타격하며, 이는 데이터베이스 모델링 품질을 평가하는 핵심 척도다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 이상 현상 (Update Anomaly) | 동시성 제어 문제 (Concurrency Issue) | 차이점 식별 기준 |
|:---|:---|:---|:---|
| 발생 원인 | 정규화 미흡에 따른 논리적 스키마 결함 | 다중 트랜잭션의 병행 접근 및 락 관리 실패 | 스키마 구조 vs 런타임 제어 |
| 발생 환경 | 단일 사용자 환경에서도 반드시 발생 | 다중 사용자 환경(트랜잭션 겹침)에서 발생 | 트랜잭션 격리 수준 무관 |
| 해결 방안 | 무손실 조인 분해(정규화) | 트랜잭션 격리수준 상향, 락(Lock) 기법 적용 | 설계자 vs DBA/개발자 |

> 요약: 이상 현상은 테이블을 쪼개어 스키마를 고쳐야 해결되며, 트랜잭션 락(Lock)으로는 방어할 수 없다.

**리스크·대응:**
- 레거시 DB 갱신 이상: 과거 반정규화된 시스템에서 불일치 축적 → 배치 검증 스크립트 기반 정합성 보정 (지표: 정합성 불일치 건수)
- 분해 시 성능 저하: 이상현상 제거를 위해 과도하게 쪼개어 조인 부하 발생 → 인덱스 최적화 및 뷰(View) 제공으로 커버 (지표: 슬로우 쿼리 비율)

**도입 후 점검 지표:**
- 품질/운영: 비정규화 테이블 내 데이터 중복도 평가 — 중복 허용 범위 이내 유지
- 무결성 지표: NULL 값이 삽입되거나 고립된 튜플 발생 수 0건 — DB 제약조건 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 논리 모델링 단계 ERD 검증: 프로젝트 초기 데이터 모델링 시 BCNF 수준까지 정규화를 원칙으로 하여 원천 차단
2. 데이터 품질 관리(DQM) 프로파일링: 운영 중인 DB 컬럼의 카디널리티 및 종속성을 역산출하여 갱신 이상 잠재 테이블 식별
3. 트리거(Trigger) 통제: 불가피하게 성능 목적 반정규화 허용 시, 갱신 시 DB 트리거를 작성해 동기화를 강제

**결론:**
- 기술사 판단: 이상 현상은 시스템 신뢰성을 근본적으로 파괴하므로, 물리 설계 전 철저한 함수 종속성 분석을 통한 3NF 이상의 정규화가 필수다.
- 향후 방향: 최근 NoSQL 환경에서는 의도적 중복을 허용하되, 애플리케이션 레벨의 이벤트 소싱 등을 통해 최종 일관성으로 이상 현상을 통제하는 패러다임이 확산 중이다.
