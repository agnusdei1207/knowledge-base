# 📖 【암기용】 개념 완전 이해

> 목적: 이상 현상을 처음 보는 사람도 중복 데이터가 왜 삽입·삭제·갱신 문제를 만드는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 한 테이블에 서로 다른 사실을 섞어 저장해 데이터 변경 시 모순이 생기는 현상
- **왜 필요한가**: 고객·주문·상품 정보를 한 테이블에 반복 저장하면 고객명 변경 1건이 1,000행 수정으로 커지고 일부 행 누락 시 불일치가 생긴다.
- **핵심 직관**: 같은 전화번호를 수첩 10곳에 적어두면 한 곳만 고쳤을 때 나머지 9곳이 틀린 정보가 되는 상황이다.

## 깊이 이해
- **배경·문제의식**: 관계형 모델은 하나의 사실을 한 곳에 저장하도록 정규화를 사용한다. 이를 어기면 함수 종속이 한 테이블 안에서 얽혀 삽입·삭제·갱신 이상이 발생한다.
- **작동 원리**: 삽입 이상은 필요한 일부 정보가 없어 새 사실을 넣지 못하는 상태, 삭제 이상은 행 삭제로 보존해야 할 사실까지 사라지는 상태, 갱신 이상은 중복 값 일부만 바뀌어 모순이 생기는 상태이다.
- **비유**: 학생 명단과 강의실 정보를 한 표에 섞으면 수강생이 0명인 강의실은 등록할 수 없고, 마지막 수강생 삭제 시 강의실 정보도 사라진다.
- **구체 예시**: `수강(학번, 학생명, 과목코드, 과목명, 교수명)`에서 과목명은 과목코드에 종속된다. 과목명 변경 시 500개 수강 행을 모두 수정하지 않으면 같은 과목코드에 두 과목명이 존재한다.
- **흔한 오해·주의점**: 이상 현상은 단순 중복 자체가 아니라 잘못된 함수 종속 배치에서 발생한다. 성능 목적의 반정규화도 원본 정규화 모델과 검증 절차가 있으면 통제 가능하다.

## 연결 개념
- 함수 종속 — 속성 간 결정 관계를 분석하는 기준
- 정규화 — 1NF, 2NF, 3NF, BCNF로 이상 현상을 제거
- 반정규화 — 통제된 중복을 허용하는 물리 설계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이상 현상은 암기 항목이 아니라 함수 종속 위반을 찾아 정규화 단계로 매핑하는 문제이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 이상 현상은 중복 저장과 함수 종속 혼재로 삽입·삭제·갱신 시 데이터 모순이 발생하는 관계형 설계 결함이다.
> 2. **가치**: 이상 현상을 식별하면 1NF~BCNF 정규화로 무결성 위반과 유지보수 비용을 줄일 수 있다.
> 3. **판단 포인트**: 삽입·삭제·갱신 사례를 함수 종속, 후보키, 정규형 위반으로 연결해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 관계형 모델링 결함 식별 역량 확인 | 삽입·삭제·갱신 이상 3종과 발생 조건 | 예시 없이 명칭만 나열 |
| 정규화 단계 매핑 확인 | 부분 종속, 이행 종속, 결정자 후보키 여부 | 1NF~3NF 차이 혼동 |
| 실무 데이터 품질 통제 확인 | 중복률, 불일치 건수, 제약 조건, 마이그레이션 | 반정규화와 설계 결함을 동일시 |

> 요약: 이 문제는 이상 3종을 사례로 설명하고 정규화 처방과 검증 지표로 연결하는 답안을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 이상 현상은 변경 시 데이터 모순이다.
- 배경: 한 테이블에 여러 주제의 사실을 섞으면 삽입 제약, 삭제 손실, 갱신 불일치가 발생한다.
- 필요성: 함수 종속, 후보키, 1NF~BCNF 정규화로 삽입·삭제·갱신 이상을 제거해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
비정규 테이블 -> 중복 속성 -> 함수 종속 혼재 -> 삽입/삭제/갱신 이상
               / 부분 종속
               / 이행 종속
               / 후보키 아닌 결정자
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 비정규 테이블 | 여러 엔터티 사실을 한 행에 저장 | 학생·과목·교수 정보 혼재 |
| 함수 종속 | 특정 속성이 다른 속성을 결정 | 과목코드 -> 과목명 |
| 중복 속성 | 같은 사실이 여러 행에 반복 | 교수명, 부서명, 상품명 반복 |
| 이상 현상 | 변경 시 모순·손실 발생 | 삽입, 삭제, 갱신 3종 |
| 정규화 처방 | 종속 관계 기준 테이블 분해 | 2NF, 3NF, BCNF 적용 |

> 요약: 이상 현상은 중복 속성과 잘못 배치된 함수 종속이 결합해 변경 작업에서 모순을 만드는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
속성 목록 수집 -> 후보키 식별 -> 함수 종속 분석 -> 이상 유형 판정 -> 정규형 분해
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 테이블의 후보키와 비키 속성 식별 | 후보키 1개 이상 도출 |
| 2 | 부분 종속·이행 종속 분석 | 2NF, 3NF 위반 여부 |
| 3 | 삽입·삭제·갱신 시나리오 작성 | 변경 1건당 영향 행 수 산정 |
| 4 | 엔터티별 테이블 분해 | 무손실 조인, 종속성 보존 |
| 5 | PK, FK, UNIQUE 제약 부여 | 중복률 0%, orphan 0건 |

> 요약: 이상 현상 분석은 후보키와 함수 종속을 먼저 찾고, 변경 시나리오로 검증한 뒤 정규화로 제거한다.

## Ⅳ. 특징

| 구분 | 삽입 이상 | 삭제 이상 | 갱신 이상 |
|:---|:---|:---|:---|
| 발생 조건 | 필수 정보 일부 부재 | 마지막 행 삭제 | 중복 행 일부 수정 |
| 대표 사례 | 수강생 없는 과목 등록 불가 | 마지막 수강 삭제로 과목 정보 손실 | 과목명 500행 중 499행만 수정 |
| 정규화 대응 | 엔터티 분리, NULL 제거 | 참조 테이블 분리 | 함수 종속 기준 분해 |
| 측정 지표 | 입력 실패 건수 | 삭제 손실 건수 | 불일치 row count |

> 요약: 이상 현상 3종은 모두 중복과 종속 관계 혼재에서 발생하며, 정규화 단계별 분해로 제거한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 통합 테이블 | 엔터티별 정규화 테이블 | 한 행에 2개 이상 주제 혼재 시 분해 |
| 비용/성능 | 조인 적음, 중복 큼 | 조인 증가, 변경 비용 감소 | 쓰기 정합성 우선 업무 |
| 운영/위험 | 수정 누락, 데이터 품질 저하 | FK·UNIQUE로 품질 통제 | 불일치 1건도 허용 불가한 기준 데이터 |

> 요약: 기준 데이터와 거래 데이터가 섞인 테이블은 정규화를 우선 적용하고, 성능 문제는 이후 인덱스·반정규화로 별도 처리한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 무손실 분해 실패 | 잘못된 분해 키 선택 | chase test, PK/FK 설계 검토 | join 후 row count 동일 |
| 종속성 보존 실패 | 제약이 여러 테이블에 분산 | UNIQUE, CHECK, trigger 적용 | 제약 위반 0건 |
| 운영 쿼리 복잡도 증가 | 테이블 수 증가 | View, ORM mapping, index 설계 | query p95 300ms 이하 |

> 요약: 정규화는 이상 현상을 줄이지만 분해 검증과 조회 성능 보완을 함께 수행해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 품질 | 중복률 0%, 불일치 0건 | profiling query, checksum |
| 무결성 | PK/FK violation 0건 | DB constraint report |
| 변경 비용 | 변경 1건 영향 행 수 1개 원본 | audit log, DML 영향도 |

> 요약: 이상 현상 제거 효과는 중복률, 제약 위반, 변경 영향 행 수로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 테이블별 후보키와 함수 종속을 도출하고 부분 종속은 2NF, 이행 종속은 3NF, 후보키 아닌 결정자는 BCNF 검토 대상으로 분류함
2. 마이그레이션 전후 row count, checksum, orphan count를 비교해 무손실 분해와 참조 무결성을 검증함
3. 정규화 후 조회 지연이 p95 300ms를 초과하면 인덱스, View, 제한적 반정규화를 순차 적용함

**결론 (2줄):**
- 기술사 판단: 기준 데이터·원장 데이터는 이상 현상 제거를 우선하고, 조회 전용 화면은 검증 가능한 복제본으로 분리함
- 향후 방향: 데이터 품질 도구와 CDC 기반 검증을 결합해 정규화 모델과 분석 모델을 분리 운영해야 함
