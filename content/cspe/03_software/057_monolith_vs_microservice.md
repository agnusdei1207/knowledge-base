## 핵심 인사이트 (3줄 요약)
- **모놀리식(Monolithic)**: 모든 비즈니스 로직(UI, 주문, 결제 등)이 하나의 거대한 코드베이스와 단일 프로세스로 동작하는 전통적인 아키텍처 (초기 개발 속도 빠름).
- **마이크로서비스(Microservice, MSA)**: 시스템을 작고 독립적인 서비스들로 쪼개어, 각 서비스가 자체 DB를 가지고 API로 통신하는 분산 아키텍처 (확장성과 민첩성 극대화).
- "MSA는 은통알이 아니다." 조직 규모가 작고 도메인이 단순할 때는 모놀리스가 정답이며, 시스템이 커지면서 배포 병목과 확장의 한계가 올 때 MSA로 점진적 전환(Strangler Pattern)을 하는 것이 정석임.

## Ⅰ. 개요 및 필요성
- **개요**: 애플리케이션의 크기와 경계를 어떻게 나눌 것인가에 대한 두 가지 상반된 아키텍처 스타일.
- **필요성**: 기존 모놀리식 시스템은 코드가 수백만 줄로 거대해지자, 작은 스펠링 하나만 고쳐도 전체 시스템을 껐다 켜야 했고 수십 명의 개발자가 코드 충돌로 고통받았음. 이를 해결하기 위해 비즈니스 도메인 단위로 시스템과 팀을 잘게 쪼개는 MSA가 탄생함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **모놀리식 아키텍처**:
  - 하나의 거대한 덩어리(EAR/WAR). DB도 하나만 사용함.
  - 내부 메서드 호출(Call)로 통신하므로 응답 속도가 매우 빠름.
- **마이크로서비스 아키텍처**:
  - 주문 서비스, 결제 서비스가 물리적으로 분리된 서버(컨테이너)에서 동작.
  - 네트워크 통신(REST, gRPC)을 통해 데이터를 주고받으며, 서비스별로 최적의 언어(Java, Node.js)와 DB(MySQL, MongoDB)를 자유롭게 선택함 (Polyglot).

```text
[ 모놀리식과 마이크로서비스 아키텍처 비교 ]

  (Monolithic Architecture)            (Microservices Architecture)
  
  [        Web Server       ]           [ API Gateway / 로드밸런서 ]
  [ +---------------------+ ]                   /         \
  [ | UI / Order / User   | ]          [ Order MSA ]    [ User MSA ]
  [ +---------------------+ ]            (Spring)        (Node.js)
              |                              |               |
       [ 통합 Oracle DB ]               [ MySQL DB ]     [ MongoDB ]
                                        (주문 전용)      (유저 전용)
```
---
## Ⅲ. 비교 및 연결
| 구분 | Monolithic (모놀리식) | Microservices (마이크로서비스) |
|---|---|---|
| **개발 및 배포** | 초기에는 매우 빠름 / 후기엔 지옥 | 초기 세팅 복잡 / 후기엔 독립 배포로 빠름 |
| **스케일링(확장)** | 전체 시스템을 통째로 복제해야 함 | 부하가 많은 '결제' 서비스만 개별 스케일링 가능 |
| **장애 격리** | 메모리 누수 발생 시 전체 시스템 다운 | 한 서비스가 죽어도 다른 서비스는 정상 동작 |
| **데이터 정합성**| 단일 DB의 트랜잭션(ACID)으로 완벽 보장 | 분산 트랜잭션(Saga, Eventual Consistency)으로 복잡함 |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **분산 시스템의 저주**: MSA를 도입하면 '네트워크 지연(Latency)', '분산 트랜잭션 처리', '통합 테스트의 어려움', '인프라 관리 비용(K8s 등)'이라는 막대한 기술적 복잡성이 발생함. 이 복잡성을 관리할 DevOps 역량과 CI/CD 자동화가 없다면 MSA 도입은 100% 실패함.
- **모놀리식 퍼스트 (MonolithFirst)**: 마틴 파울러(Martin Fowler)도 "처음부터 MSA로 시작하지 마라"고 경고함. 도메인 지식이 불명확한 초기 스타트업은 모놀리스로 빠르게 시장을 검증하고, 트래픽이 폭발할 때 MSA로 찢는 것이 가장 실무적인 최적의 패스임.
---
## Ⅴ. 기대효과 및 결론
- 모놀리식이 '하나의 거대한 항공모함'이라면, 마이크로서비스는 '수백 대의 날렵한 쾌속정 함대'임.
- MSA는 기술의 문제가 아니라 조직의 문제(콘웨이의 법칙)이며, 자율적이고 독립적인 작은 팀들이 각자의 서비스를 소유할 때 비로소 그 진가가 발휘됨.

### 👶 어린이를 위한 3줄 비유 설명
1. 모놀리식은 머리, 팔, 다리가 하나로 찰흙처럼 뭉쳐진 '거대 로봇'이에요. 팔 하나만 고장 나도 로봇 전체를 수리센터에 맡겨야 해요.
2. 마이크로서비스는 레고 블록으로 조립한 '합체 로봇'이에요! 머리팀, 팔팀, 다리팀이 따로 있어서 고장 난 팔만 쏙 빼서 1초 만에 새 걸로 갈아 끼울 수 있죠.
3. 대신 합체 로봇은 부품끼리 무전기(네트워크)로 통신해야 해서 만드는 방법이 훨씬 어렵답니다!
