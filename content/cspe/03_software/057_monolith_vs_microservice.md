## 미리 알고가기

- 모놀리식은 하나의 배포 단위로 시스템을 구성하는 구조임
- 마이크로서비스는 서비스별 독립 배포와 확장을 지향하는 구조임
- 선택 기준은 규모보다 변경 방향과 운영 역량임

## Ⅰ. 개요

- **정의/개념**: 모놀리식은 애플리케이션 기능을 하나의 코드베이스와 배포 단위로 통합한 구조이고, 마이크로서비스는 기능을 독립 서비스로 분리해 개별 배포와 확장을 가능하게 하는 분산 구조임
- **배경/필요성**: 시스템 규모와 팀 수와 배포 빈도가 커질수록 단일 구조가 가진 장점과 한계가 달라지므로, 아키텍처 선택을 기술 유행이 아니라 조직과 서비스 변화 속도에 맞춰 판단해야 함

## Ⅱ. 특징

- 모놀리식은 단순한 개발과 운영과 트랜잭션 처리에 유리함
- 마이크로서비스는 팀 자율성과 서비스별 확장에 유리함
- 모놀리식은 배포 충돌과 확장 비효율이 커질 수 있음
- 마이크로서비스는 네트워크와 데이터 정합성과 운영 복잡도가 크게 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 모놀리식 | 마이크로서비스 |
|:---|:---|:---|
| 배포 단위 | 단일 애플리케이션 | 서비스별 독립 배포 |
| 데이터 처리 | 단일 DB와 트랜잭션 유리 | 서비스별 데이터 소유 |
| 장점 | 단순성, 빠른 초기 개발 | 독립 확장, 팀 자율성 |
| 한계 | 대규모 변경 충돌 | 운영 복잡도, 분산 정합성 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Codebase Boundary | 모놀리식은 하나의 코드베이스로 단순성을 얻고 MSA는 분리된 저장소와 서비스 경계를 통해 독립성을 얻음 |
| Deployment Unit | 배포 단위 차이가 릴리스 속도와 장애 영향 범위를 직접 결정함 |
| Data Ownership | 모놀리식은 통합 트랜잭션에 유리하고 MSA는 데이터 소유 분리로 자율성을 확보함 |
| Operational Layer | MSA는 관측과 네트워크와 자동화 계층이 필수이며 모놀리식은 비교적 단순한 운영으로도 유지 가능함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변화 요인 분석  | --> | 배포 단위 선택 | --> | 데이터 경계 정의 | --> | 운영 비용 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변화 요인 분석**: 기능 변경 빈도와 팀 구조와 확장 패턴을 파악함
2. **배포 단위 선택**: 단일 배포 또는 서비스 분리를 결정함
3. **데이터 경계 정의**: 트랜잭션과 데이터 소유 구조를 설계함
4. **운영 비용 검증**: 자동화와 관측과 장애 대응 비용을 평가함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 아직 단순한 시스템을 성급히 MSA로 나누면 서비스 간 통신과 운영 복잡도만 커질 수 있음
   - 해결방안: 분해 기준선을 두고 architecture fit score와 operational overhead per service로 검증함
2. 문제: 커진 모놀리식을 끝까지 유지하면 배포 충돌과 모듈 간 결합이 누적될 수 있음
   - 해결방안: 모듈화와 점진 분리를 수행하고 deployment coupling rate와 build lead time으로 검증함
3. 문제: 아키텍처보다 조직 역량이 부족하면 어떤 구조를 선택해도 지속 운영이 흔들릴 수 있음
   - 해결방안: 플랫폼 자동화와 팀 책임 정렬을 병행하고 ownership clarity score와 incident MTTR로 검증함

## Ⅶ. 적용 사례

- 초기 제품 서비스에서는 모놀리식 구조를 유지하고 확인 지표는 build lead time과 change failure rate임
- 대형 전자상거래 플랫폼에서는 점진적으로 MSA를 도입하고 확인 지표는 deployment coupling rate와 operational overhead per service임
- 아키텍처 전환 검토 조직에서는 팀 역량을 함께 평가하고 확인 지표는 architecture fit score와 ownership clarity score임

## Ⅷ. 결론

모놀리식과 마이크로서비스의 선택은 규모 자랑이 아니라 변경 비용과 배포 독립성과 운영 복잡도 사이에서 어디에 최적점을 둘지 정하는 문제임.
