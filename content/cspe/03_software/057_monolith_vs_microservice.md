## 미리 알고가기

- 모놀리식은 기능을 하나의 코드베이스와 배포 단위로 묶는 구조임
- 마이크로서비스는 기능을 독립 서비스로 나눠 개별 배포와 확장을 지향하는 구조임
- 선택 기준은 변경 단위와 운영 역량과 데이터 경계임

## 작성 근거(검토용)

- 모놀리식·마이크로서비스는 배포 단위, 데이터 소유, 팀 책임, 운영 부담을 핵심 비교축으로 선정함
- 구성은 코드·배포·데이터 경계와 운영 계층의 관계를 중심으로 제시함
- 실무 판단은 빌드 시간, 동시 배포율, 서비스 간 호출 수, 데이터 불일치 건수로 구체화함

## Ⅰ. 개요

- **정의/개념**: 모놀리식은 기능을 하나의 배포 단위로 통합하고, 마이크로서비스는 기능을 독립 배포 가능한 서비스로 분리한 구조임
- **배경/필요성**: 기능별 변경 빈도와 팀 책임과 데이터 소유 방식에 따라 배포 경계와 운영 비용이 달라지므로 구조 선택 기준이 필요함

## Ⅱ. 특징

- 모놀리식은 개발과 배포와 트랜잭션 구성이 단순함
- 마이크로서비스는 서비스별 소유 팀과 배포·확장 단위를 분리함
- 모놀리식은 코드와 배포가 커질수록 변경 충돌이 누적되기 쉬움
- 마이크로서비스는 네트워크 호출과 데이터 일관성과 관측 비용이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 모놀리식 | 마이크로서비스 |
|:---|:---|:---|
| 배포 단위 | 애플리케이션 전체를 한 번에 배포함 | 서비스별로 필요한 부분만 따로 배포함 |
| 데이터 처리 | 단일 저장소에서 통합 트랜잭션을 처리함 | 서비스별 데이터 소유와 일관성 처리가 필요함 |
| 소유·확장 방식 | 단일 코드·배포 단위를 공동 운영 | 서비스별 팀이 코드·데이터·배포·확장 책임 보유 |
| 구조상 한계 | 일부 기능 수정도 전체 릴리스에 영향을 주기 쉬움 | 운영 자동화와 장애 분석과 데이터 일관성 관리가 어려워짐 |

> 요약: 단일 배포와 통합 트랜잭션은 모놀리식, 서비스별 배포·데이터 소유는 마이크로서비스가 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 코드베이스 경계 | 모놀리식은 하나의 코드베이스로 단순성을 얻고 마이크로서비스는 서비스 경계로 독립성을 얻음 |
| 배포 단위 | 배포 단위 차이가 릴리스 속도와 장애 영향 범위를 직접 바꿈 |
| 데이터 소유 | 단일 저장소 또는 서비스별 저장소 소유 방식이 데이터 일관성 처리 범위를 결정함 |
| 운영 계층 | 마이크로서비스는 분산 관측과 배포 자동화 계층을 추가하고 모놀리식은 단일 배포 흐름을 운영함 |

> 요약: 코드·배포·데이터를 하나로 관리하면 모놀리식, 서비스 경계별로 분리하면 마이크로서비스 구조가 됨.

## Ⅵ. 실무 사례

1. 초기 업무 시스템은 모듈형 모놀리식으로 구성하고 빌드 시간·동시 배포율을 확인함
2. 대형 플랫폼은 서비스별 코드·저장소 소유를 분리하고 호출 수·데이터 불일치 건수를 확인함

## Ⅶ. 결론

모놀리식과 마이크로서비스는 배포 독립성·데이터 소유·운영 복잡도의 균형에 따라 선택함
