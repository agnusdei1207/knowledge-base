## 미리 알고가기

- 모놀리식은 기능을 하나의 코드베이스와 배포 단위로 묶는 구조임
- 마이크로서비스는 기능을 독립 서비스로 나눠 개별 배포와 확장을 지향하는 구조임
- 선택 기준은 규모 자체보다 변경 속도와 운영 역량과 데이터 경계임

## Ⅰ. 개요

- **정의/개념**: 모놀리식은 애플리케이션 기능을 하나의 배포 단위로 통합한 구조이고, 마이크로서비스는 기능을 여러 서비스로 분리해 독립 배포와 독립 확장을 가능하게 한 분산 구조임.
- **배경/필요성**: 시스템이 커질수록 배포 충돌과 데이터 경계와 조직 책임 문제가 달라지므로, 아키텍처 선택을 기술 유행이 아니라 서비스 변화 방식과 운영 능력에 맞춰 판단해야 함.

## Ⅱ. 특징

- 모놀리식은 개발과 배포와 트랜잭션 구성이 단순함
- 마이크로서비스는 서비스별 소유 팀과 배포·확장 단위를 분리함
- 모놀리식은 코드와 배포가 커질수록 변경 충돌이 누적되기 쉬움
- 마이크로서비스는 네트워크 호출과 데이터 정합성과 관측 비용이 커짐

## Ⅲ. 종류 및 비교

| 구분 | 모놀리식 | 마이크로서비스 |
|:---|:---|:---|
| 배포 단위 | 애플리케이션 전체를 한 번에 배포함 | 서비스별로 필요한 부분만 따로 배포함 |
| 데이터 처리 | 단일 저장소와 통합 트랜잭션을 구성하기 쉬움 | 서비스별 데이터 소유를 나눠야 하므로 정합성 설계가 필요함 |
| 소유·확장 방식 | 단일 코드·배포 단위를 공동 운영 | 서비스별 팀이 코드·데이터·배포·확장 책임 보유 |
| 구조상 한계 | 일부 기능 수정도 전체 릴리스에 영향을 주기 쉬움 | 운영 자동화와 장애 분석과 데이터 일관성 관리가 어려워짐 |

> 요약: 모놀리식과 마이크로서비스의 차이는 코드 분량보다 배포 경계와 운영 비용을 어디에 둘 것인가에 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 코드베이스 경계 | 모놀리식은 하나의 코드베이스로 단순성을 얻고 마이크로서비스는 서비스 경계로 독립성을 얻음 |
| 배포 단위 | 배포 단위 차이가 릴리스 속도와 장애 영향 범위를 직접 바꿈 |
| 데이터 소유 | 단일 저장소 중심인지 서비스별 소유 분리인지가 정합성 처리 방식을 결정함 |
| 운영 계층 | 마이크로서비스는 관측과 자동화 계층이 필수이고 모놀리식은 비교적 단순한 운영으로도 유지 가능함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변화 요인 분석  | --> | 배포 단위 선택 | --> | 데이터 경계 정의 | --> | 운영 비용 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변화 요인 분석**: 기능 변경 빈도와 팀 구조와 확장 패턴을 파악함
2. **배포 단위 선택**: 단일 배포가 유리한지 서비스 분리가 필요한지 정함
3. **데이터 경계 정의**: 통합 트랜잭션과 서비스별 소유 구조를 설계함
4. **운영 비용 검증**: 자동화와 관측과 장애 대응 능력을 함께 평가함

## Ⅵ. 실무 적용 및 유의점

1. 초기 제품이나 규칙이 단순한 내부 시스템에서는 모놀리식이 더 실용적이지만 코드와 배포가 커지기 시작하면 충돌이 빠르게 늘 수 있으므로 모듈 경계를 먼저 정리하고 빌드 소요시간과 동시 배포 비율로 확인함
2. 대형 전자상거래나 플랫폼처럼 팀과 기능이 빠르게 늘어나는 환경에서는 마이크로서비스가 유리하지만 데이터 경계가 약하면 운영 부담만 커지므로 서비스 책임과 저장소 소유를 함께 재설계하고 서비스 간 호출 수와 정합성 사고 건수로 확인함

## Ⅶ. 결론

모놀리식과 마이크로서비스의 선택은 구조 이름이 아니라 변경 비용과 배포 독립성과 운영 복잡도 사이의 균형을 정하는 문제임.
