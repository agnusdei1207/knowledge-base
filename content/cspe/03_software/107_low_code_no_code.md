## Ⅰ. 개요
- **정의**: 최소한의 코딩 또는 코딩 없이 시각적 도구로 애플리케이션을 개발하는 플랫폼임
- **배경/필요성**: 개발자 부족과 디지털 전환 수요 증가로 비개발자의 앱 개발 참여가 필요함
- **비유**: 파워포인트로 슬라이드를 만들듯 드래그앤드롭으로 앱을 조립하는 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Low-Code vs No-Code 차이·적용 범위 | 시민 개발자 개념과 거버넌스 | RPA(108 참조)와의 관계(업무 자동화 관점) |

> 요약: 시각적 개발 환경으로 앱 개발 진입장벽을 낮추는 플랫폼임

## Ⅱ. 구성요소
```text
Low-Code/No-Code Platform
  +-- Visual Designer (시각적 편집기)
  |     +-- UI Builder / Workflow Editor / Data Modeler
  +-- Runtime Engine (실행 엔진)
  |     +-- 앱 해석/실행/배포
  +-- Integration Layer (연동 계층)
        +-- API 커넥터 / 외부 시스템 연동
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Visual Designer | 드래그앤드롭으로 UI·로직·데이터를 설계하는 편집기 | 블록 조립 놀이판 |
| Runtime Engine | 시각적으로 정의된 앱을 해석·실행하는 엔진 | 블록 조립 결과를 작동시키는 모터 |
| Integration Layer | 외부 API·DB와 연동하는 커넥터 계층 | 다른 장난감과 연결하는 어댑터 |

> 요약: 시각적 설계, 실행 엔진, 연동 계층의 3계층으로 구성됨

## Ⅲ. 절차
```text
요구 정의 --> 시각적 설계 --> 테스트/검증 --> 배포/운영
```
- 1단계: 업무 요구를 분석하고 플랫폼 적합성(복잡도·연동 범위)을 판단함
- 2단계: Visual Designer로 UI·비즈니스 로직·데이터 모델을 구성함
- 3단계: 프리뷰·샌드박스 환경에서 기능·보안·성능을 검증함
- 4단계: 승인 후 운영 환경에 배포하고 버전·접근 권한을 관리함

> 요약: 요구 분석부터 배포까지 4단계로 앱을 개발함

## Ⅳ. 문제점
- 벤더 종속: 플랫폼 고유 형식 — 타 플랫폼 이관 시 재개발이 필요함
- 복잡 로직 한계: 시각적 도구의 표현력 제약 — 고도 비즈니스 로직 구현이 어려움
- 섀도 IT 위험: 비개발자의 무분별한 앱 생산 — 보안·품질 거버넌스 사각지대가 발생함

> 요약: 벤더 종속·표현력 한계·거버넌스 부재가 핵심 리스크임

## Ⅴ. 개선방안
1. 단기: 멀티 플랫폼 지원 표준(OData, OpenAPI)을 적용하여 이식성을 확보함
2. 중기: Pro-Code 확장 포인트를 활용하여 복잡 로직을 커스텀 코드로 보완함
3. 장기: CoE(Center of Excellence)를 설치하여 시민 개발자 거버넌스 체계를 운영함

> 요약: 표준 기반 이식성, 코드 확장, 거버넌스 체계 순으로 리스크를 관리함

## Ⅵ. 전망
- 발전 방향: AI 코드 생성(Copilot)과 결합하여 자연어 기반 앱 개발로 진화 중임
- 기술사적 판단: 개발자 생산성과 비개발자 역량 확장의 교차점에 위치한 기술임
- 기술사 제언: 거버넌스와 개발 민주화의 균형 확보가 도입 성공의 핵심임
