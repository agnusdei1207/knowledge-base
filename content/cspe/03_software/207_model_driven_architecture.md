## Ⅰ. 개요
- 특정 기술 플랫폼에 종속되지 않는 모델을 중심으로 소프트웨어를 개발하는 방식임
- OMG에서 제안했으며, 모델 변환(Transformation)을 통해 소스코드를 자동 생성함
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | PIM, PSM, CIM, 모델 변환 기술, 상호운용성 | 설계도만 그리면 건물이 지어지는 자동 건축 |

## Ⅱ. 구성요소
- 추상화 수준에 따른 CIM, PIM, PSM 모델 체계임
[CIM: 비즈니스] -> [PIM: 플랫폼 독립] -> [PSM: 플랫폼 종속] -> [Code]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| PIM | 특정 기술(Java, .NET 등)과 무관한 핵심 로직 모델 | 건물의 기본 구조도 |
| PSM | 특정 플랫폼 기술 요소가 반영된 상세 모델 | 배관/전기 설비가 포함된 시공도 |
| 모델 변환 | PIM을 PSM으로, PSM을 코드로 변환하는 자동화 규칙 | 번역기 또는 컴파일러 |
> 요약: 모델링이 곧 프로그래밍이 되는 추상화 기반 개발 패러다임임

## Ⅲ. 절차
- 모델의 점진적 구체화 및 자동 변환 절차임
[비즈니스 분석] -> [PIM 설계] -> [PSM 변환] -> [코드 생성]
- 4단계 설명
1) PIM 작성: UML 등을 활용하여 시스템의 기능과 데이터 구조를 기술함
2) 매핑 정의: PIM의 요소를 대상 플랫폼(예: Spring Boot)의 요소로 매핑함
3) 자동 변환: MDA 도구를 사용하여 정해진 규칙에 따라 PSM 및 골격 코드 생성함
4) 상세 구현: 생성된 코드에 비즈니스 세부 로직을 추가하여 완성함
> 요약: 플랫폼 기술 변화에 유연하게 대응하며 개발 생산성을 혁신함

## Ⅳ. 문제점
- 고도의 모델링 역량이 요구되며, 학습 곡선(Learning Curve)이 매우 높음 (원인: 기술 복잡도)
- 생성된 코드와 수작업 코드 간의 동기화(Round-trip) 관리가 어려움 (원인: 양방향 변경)

## Ⅴ. 개선방안
- (단기) 도메인 특화 언어(DSL)를 활용하여 모델링의 직관성 확보함
- (중기) 모델과 코드 간 일관성을 유지해주는 동기화 엔진 고도화함
- (장기) 요구사항(자연어)에서 PIM을 추출하는 지능형 모델링 도구 도입함

## Ⅵ. 전망
- 로우코드/노코드(LCNC) 플랫폼의 기반 기술로서 MDA의 가치가 재조명될 것임
- 향후 AI가 모델 간의 최적 변환 규칙을 생성하는 'AI-Enabled MDA'로 진화할 전망임
