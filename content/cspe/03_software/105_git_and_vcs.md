## Ⅰ. 개요
- 정의: Git and VCS의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Local Repo] <--> [Staging] <--> [Commit] <--> [Remote Repo]
     (Work)         (Index)       (Local)       (GitHub)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 분산 저장소 | 모든 개발자가 전체 이력을 보유함 | 개별 복사본 |
| 브랜치 | 독립적인 작업을 위한 가지치기 | 평행 우주 |
| 머지/리베이스 | 변경 사항을 통합하는 작업 | 합치기 |

> 요약: 소스 코드의 이력을 분산 관리하는 현대적 VCS임.

## Ⅲ. 절차
- ASCII 흐름도
  Clone -> Branch -> Commit -> Push -> Pull Request -> Merge

1. 워크플로우 설정: Git-flow, GitHub-flow 등 전략 선정함.
2. 로컬 작업: 기능 단위 커밋 및 원자적 변경 수행함.
3. 협업 수행: Pull Request를 통한 코드 리뷰 및 검증함.
4. 릴리스 관리: 태그(Tag) 활용하여 버전별 릴리스 관리함.

> 요약: 브랜치 전략을 통한 병렬 개발 및 협업 극대화임.

## Ⅳ. 문제점
- 대용량 바이너리 파일 관리 시 성능 저하 및 저장소 비대화함.
- 복잡한 머지 충돌(Merge Conflict) 시 코드 손실 우려 존재함.

## Ⅴ. 개선방안
- Git LFS (Large File Storage) 활용하여 대용량 파일 분리 관리함.
- 지속적 통합(CI) 빈도 강화로 충돌 범위를 최소화 및 즉시 해결함.

## Ⅵ. 전망
- 클라우드 IDE와의 결합으로 개발 환경의 완전한 코드화 가속화됨.
- CSF: 팀 규모와 릴리스 주기에 최적화된 브랜치 전략(Flow) 확립임.
