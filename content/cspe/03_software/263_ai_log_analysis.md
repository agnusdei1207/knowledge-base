## Ⅰ. 개요
- **정의**: AI가 시스템·애플리케이션 로그를 자동 파싱·분류·이상 탐지하여 운영 인사이트를 도출하는 기법
- **배경/필요성**: 마이크로서비스·클라우드 환경에서 로그 볼륨이 기하급수적으로 증가하여 수동 분석이 불가능해짐
- **비유**: 수만 페이지의 진료 기록에서 이상 징후를 자동으로 찾아내는 AI 판독의와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 로그 분석의 자동화·지능화 이해 | 이상 탐지(Anomaly Detection) 원리 | 단순 키워드 검색과의 차이 명시 |

> 요약: AI 로그 분석은 대규모 로그에서 패턴을 학습하여 이상을 자동 탐지하는 운영 지능화 기법임

## Ⅱ. 구성요소
```text
[Log Sources] --수집--> [Log Pipeline]
                            |
               +------------+------------+
               |            |            |
               v            v            v
         [Parser]    [Embedding]   [Anomaly Detector]
               |            |            |
               v            v            v
         [Structured]  [Vector DB]  [Alert/Dashboard]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Parser | 비정형 로그를 정형 필드로 변환함 | 속기록을 표준 양식으로 정리하는 것 |
| Embedding | 로그 메시지를 벡터로 변환하여 의미 유사도를 계산함 | 문장을 좌표로 변환하여 거리 비교하는 것 |
| Anomaly Detector | 정상 패턴에서 벗어난 로그 시퀀스를 탐지함 | 심전도에서 부정맥을 감지하는 것 |

> 요약: 파싱-임베딩-이상탐지 3개 모듈이 비정형 로그를 정형화하고 이상을 식별함

## Ⅲ. 절차
```text
로그 수집 --> 파싱/정규화 --> 패턴 학습 --> 이상 탐지/알림
    |              |              |              |
    v              v              v              v
  Agent수집    템플릿추출     베이스라인      편차임계판단
```
- 1단계: 분산 환경의 로그를 에이전트·사이드카로 중앙 수집함
- 2단계: 로그 템플릿을 추출하고 필드를 정규화함
- 3단계: 정상 상태의 로그 패턴을 학습하여 베이스라인을 수립함
- 4단계: 베이스라인 대비 편차가 임계값을 초과하면 이상으로 판정하고 알림을 발생함

> 요약: 수집-정규화-학습-탐지의 4단계 파이프라인으로 이상 로그를 자동 식별함

## Ⅳ. 문제점
- 로그 포맷 파편화: 서비스별 로그 형식이 상이함 — 파서 유지보수 비용이 증가함
- 개념 드리프트: 시스템 변경으로 정상 패턴이 변함 — 베이스라인이 무효화되어 오탐이 증가함
- 알림 피로: 과다한 경보가 발생함 — 운영자가 중요 알림을 간과하게 됨

> 요약: 포맷 파편화·드리프트·알림 피로가 AI 로그 분석의 주요 장애 요인임

## Ⅴ. 개선방안
1. 단기: OpenTelemetry 등 표준 로그 포맷을 도입하여 파싱 복잡도를 감소
2. 중기: 온라인 학습 기반 베이스라인 자동 갱신으로 개념 드리프트에 적응
3. 장기: 알림 상관분석·자동 그룹핑으로 중복 경보를 통합하여 알림 피로를 해소

> 요약: 포맷 표준화-적응형 학습-알림 통합으로 단계적 고도화가 필요함

## Ⅵ. 전망
- 발전 방향: LLM 기반 자연어 질의로 로그를 대화형 탐색하는 방향으로 진화함
- 기술사적 판단: AIOps의 핵심 구성 요소로서 관제 자동화의 기반 기술이 될 것임
- 기술사 제언: 로그 표준화와 AI 분석 도구를 관측 가능성(Observability) 전략에 통합할 필요
