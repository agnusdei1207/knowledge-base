## Ⅲ. 절차
- ASCII 흐름도
  Training -> Design -> Implementation -> Verification -> Release

1. 보안 교육: 개발자 대상 시큐어 코딩 및 보안 인식 교육함.
2. 위협 분석: STRIDE 모델 등을 활용한 설계 보안 검토함.
3. 시큐어 코딩: 정적 분석 도구 활용하여 취약 소스 제거함.
4. 보안 검증: 동적 분석 및 침투 테스트로 최종 무결성 확인함.

> 요약: 사후 조치 위주에서 예방 중심의 보안 체계로의 전환임.

## Ⅳ. 문제점
- 보안 활동 추가에 따른 개발 기간 연장 및 비용 상승 발생함.
- 보안 전문 인력 부족으로 실질적인 위협 분석 수행의 한계임.

## Ⅴ. 개선방안
- DevSecOps 파이프라인 구축을 통한 보안 검점 자동화 및 가속화함.
- 오픈 소스 취약점 관리(SCA) 도구 연동으로 공급망 보안 강화함.

## Ⅵ. 전망
- 공급망 보안(SBOM) 및 AI 보안 비서와의 결합으로 지능화됨.
- CSF: 개발자의 보안 역량 내재화와 경영진의 보안 투자 의지임.
