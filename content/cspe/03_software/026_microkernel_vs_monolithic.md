## 미리 알고가기

- 모놀리식 커널은 핵심 서비스가 커널 공간에 함께 포함되는 구조임
- 마이크로커널은 최소 기능만 커널에 두고 나머지를 사용자 공간 서버로 분리함
- 커널 기능의 배치 위치에 따라 호출 경로, 장애 전파 범위, 서비스 교체 방식이 달라짐

## Ⅰ. 개요

- **정의/개념**: 모놀리식 커널은 프로세스 관리와 메모리 관리와 파일시스템과 장치 드라이버를 하나의 큰 커널에 통합한 구조이고, 마이크로커널은 최소한의 핵심 기능만 커널에 두고 나머지 서비스를 사용자 공간으로 분리한 구조임
- **배경/필요성**: 운영체제는 성능과 확장성과 안정성 사이 균형이 필요하므로, 어떤 기능을 커널 안에 넣고 어떤 기능을 분리할지에 따라 전체 아키텍처 품질이 달라짐

## Ⅱ. 특징

- 모놀리식 커널은 직접 호출 경로가 짧아 성능에 유리함
- 마이크로커널은 서비스 분리로 장애 격리와 유지보수성이 좋음
- 마이크로커널은 IPC 비용이 커질 수 있고 모놀리식은 커널 결함 영향 범위가 큼
- 선택 기준은 시스템 목적이 범용 성능인지 고신뢰 분리인지에 따라 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 모놀리식 커널 | 마이크로커널 |
|:---|:---|:---|
| 구조 | 핵심 서비스 통합 | 최소 커널과 사용자 공간 서버 분리 |
| 호출 경로 | 커널 내부 직접 호출 | 사용자 공간 서버 간 IPC 경유 |
| 장애 영향 | 드라이버·서비스 결함이 커널 주소 공간에 전파 | 사용자 공간 서비스별 중단·재시작 가능 |
| 대표 환경 | 범용 서버·데스크톱 OS | 안전·격리 요구 임베디드·제어 OS |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Kernel Core | 모놀리식은 대부분 기능을 포함하고 마이크로커널은 스케줄링과 IPC 같은 최소 기능만 유지함 |
| User-space Service | 마이크로커널에서 파일시스템과 드라이버를 분리해 장애 격리와 업데이트 유연성을 높임 |
| IPC Path | 마이크로커널 구조에서 서비스 간 협력을 가능하게 하며 성능과 설계 복잡도의 핵심이 됨 |
| Driver Placement | 드라이버를 어디에 둘지에 따라 성능과 안정성 경계가 직접 달라짐 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 시스템 요청    | --> | 커널 기능 판별 | --> | 직접 처리 또는 IPC | --> | 결과 반환      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **시스템 요청**: 응용 프로그램이 파일이나 장치나 프로세스 관련 요청을 생성함
2. **커널 기능 판별**: 커널이 자체 처리 대상인지 외부 서비스 위임 대상인지 판단함
3. **직접 처리 또는 IPC**: 모놀리식은 직접 처리하고 마이크로커널은 사용자 공간 서버와 IPC를 수행함
4. **결과 반환**: 처리 결과를 다시 응용 프로그램에 돌려줌

## Ⅵ. 실무 적용 및 유의점

1. 범용 서버와 데스크톱 OS는 모놀리식 구조가 유리하지만 드라이버 결함이 커널 전체 장애로 번질 수 있으므로 모듈화와 격리 시험을 병행하고 kernel panic rate와 driver fault impact로 확인함
2. 고신뢰 임베디드나 제어 OS는 마이크로커널이 맞지만 IPC 경로가 길어지면 지연이 커지므로 서비스 분리 범위와 IPC 최적화를 함께 설계하고 IPC latency와 recovery time으로 확인함

## Ⅶ. 결론

커널 구조 선택은 철학 논쟁이 아니라 성능 경로와 장애 격리 경계를 어디에 둘지 정하는 운영체제 아키텍처 결정임.
