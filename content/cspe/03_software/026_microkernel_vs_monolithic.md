## Ⅰ. 개요
- **정의**: 커널 설계 시 서비스 배치 범위에 따라 구분되는 두 가지 OS 아키텍처
- **배경/필요성**: 커널이 제공하는 기능 범위가 안정성·성능·유지보수성을 결정하므로 구조 선택이 중요함
- **비유**: 모놀리식은 모든 부서가 한 건물(커널)에 있는 대기업, 마이크로커널은 본사(최소 커널)+외주(사용자 서비스)와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 커널 아키텍처 비교 역량 | IPC 오버헤드 vs 모듈 격리 트레이드오프 | Linux는 모놀리식이나 모듈 적재 기능으로 혼합 특성을 가짐 |

> 요약: 커널 내 서비스 범위에 따른 성능·안정성 트레이드오프를 비교하는 주제임

## Ⅱ. 구성요소
```text
Monolithic                 Microkernel
+-----------------+        +----------+
| App             |        | App      |
+-----------------+        +----------+
| FS  Net  Driver |        | FS | Net |  <-- User Space
|    (Kernel)     |        +----+-----+
+-----------------+        | IPC, Sched |  <-- Kernel Space
| Hardware        |        +------------+
+-----------------+        | Hardware   |
                           +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 모놀리식 커널 | FS·네트워크·드라이버를 모두 커널 공간에 포함 | 전 부서 한 건물 |
| 마이크로커널 | IPC·스케줄링·메모리 관리만 커널에 포함 | 본사는 최소 인원 |
| IPC(프로세스 간 통신) | 마이크로커널에서 사용자 서비스 간 메시지 전달 | 부서 간 공문 전달 |
| 커널 모듈(LKM) | 모놀리식에서 런타임에 기능을 동적 적재/제거 | 필요 시 파견 인력 투입 |

> 요약: 커널 공간의 서비스 포함 범위와 IPC 의존도가 두 구조의 핵심 차이임

## Ⅲ. 절차
```text
모놀리식: App --> Syscall --> Kernel(직접 호출) --> HW
마이크로: App --> IPC --> User Server --> IPC --> Kernel --> HW
```
- 1단계: 애플리케이션이 시스템 호출(syscall)로 OS 서비스를 요청
- 2단계: 모놀리식은 커널 내 함수 호출로 처리, 마이크로커널은 IPC 메시지로 사용자 서버에 전달
- 3단계: 서비스 처리 후 결과를 커널 경유(모놀리식) 또는 IPC 응답(마이크로커널)으로 반환
- 4단계: 필요 시 HW 접근은 커널 공간에서 수행 후 결과를 상위 계층에 전달

> 요약: 모놀리식은 커널 내 직접 호출, 마이크로커널은 IPC 경유로 서비스를 처리함

## Ⅳ. 문제점
- 모놀리식 안정성: 드라이버 버그가 커널 전체 크래시 유발 — 단일 장애점이 됨
- 마이크로커널 성능: IPC 왕복 비용 — 서비스 호출마다 컨텍스트 스위치 2회 이상 발생
- 모놀리식 유지보수: 커널 코드 수백만 줄 — 모듈 간 의존성으로 변경 영향 범위가 큼

> 요약: 모놀리식의 안정성·유지보수 문제와 마이크로커널의 IPC 성능 문제가 핵심 과제임

## Ⅴ. 개선방안
1. 단기: 모놀리식에 장애 격리 드라이버 프레임워크(예: Linux eBPF 검증) 적용으로 안정성 향상
2. 중기: 마이크로커널에 동기 IPC 최적화(레지스터 기반 전달) 적용으로 전환 비용 저감
3. 장기: 모놀리식 커널의 점진적 모듈 분리(Unikernel/Library OS)로 유지보수성 개선

> 요약: 드라이버 격리, IPC 최적화, 모듈 분리로 양쪽 구조의 약점을 보완함

## Ⅵ. 전망
- 발전 방향: 하이브리드 커널(macOS XNU, Windows NT)처럼 두 구조의 장점을 결합하는 추세
- 기술사적 판단: 자동차·IoT 등 안전 필수 도메인에서 마이크로커널(seL4 등) 채택 증가
- 기술사 제언: 도메인 요구사항(실시간성·안전성·성능)에 따라 커널 구조를 선택 필요
