# 📖 【암기용】 개념 완전 이해

> 목적: RPA를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 사람이 반복 수행하는 화면 조작, 입력, 조회, 파일 처리를 소프트웨어 봇으로 자동화하는 기술
- **왜 필요한가**: 레거시 시스템은 API가 없고 업무 담당자는 복사·붙여넣기·엑셀 정리 같은 반복 작업에 시간을 쓴다. RPA는 시스템 변경 없이 사용자 화면 수준에서 자동화를 제공한다.
- **핵심 직관**: 신입 직원에게 매뉴얼을 주고 같은 화면 조작을 반복시키는 것을 소프트웨어 봇이 대신하는 구조이다.

## 깊이 이해
- **배경·문제의식**: 기업 업무는 ERP, 그룹웨어, 엑셀, 웹 포털이 얽혀 있다. API 연계가 없거나 변경 비용이 높으면 화면 기반 자동화가 현실적인 대안이 된다.
- **작동 원리**: 봇이 화면 요소를 인식하고 로그인, 조회, 입력, 파일 다운로드, 메일 발송을 순서대로 수행한다. 스케줄러, 자격증명 금고, 예외 처리, 로그가 운영 품질을 결정한다.
- **비유**: 엘리베이터 버튼을 사람이 누르던 절차를 자동 버튼 장치가 정해진 순서대로 누르는 것과 같다.
- **구체 예시**: 매일 09시에 ERP 매출 파일을 내려받아 엑셀 검증 후 회계 시스템에 업로드하고, 실패 시 담당자에게 티켓을 생성한다.
- **흔한 오해·주의점**: RPA는 근본적인 시스템 통합을 대체하지 않는다. 화면 UI가 자주 바뀌면 봇 실패율이 커지므로 API 전환 후보를 함께 식별해야 한다.

## 연결 개념
- BPM - 업무 프로세스 모델링과 개선
- IPA - RPA에 OCR, NLP, AI 의사결정을 결합
- API Integration - 장기적으로 화면 자동화를 대체할 연계 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: RPA는 단순 자동 클릭이 아니라 대상 업무 선정, 봇 운영, 권한 통제, 예외 처리 기준이 포함된 업무 자동화 체계이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RPA는 사람의 반복 화면 조작과 규칙 기반 업무를 소프트웨어 봇으로 수행하는 프로세스 자동화 기술이다.
> 2. **가치**: 월 1,000건 이상 반복 업무에서 처리 시간, 오류율, 감사 로그를 수치로 관리할 수 있다.
> 3. **판단 포인트**: 규칙성, 예외율, UI 변경 빈도, 권한 통제, API 전환 가능성을 기준으로 대상 업무를 선별한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 업무 자동화 이해 확인 | 봇, 스케줄러, Orchestrator, Credential Vault | 매크로와 동일시 |
| 적용 대상 판단 확인 | 반복성, 규칙성, 예외율, 처리량 | 모든 업무 자동화 가능으로 서술 |
| 운영·통제 확인 | 권한, 로그, 예외 처리, 변경 관리 | 계정 공유와 감사 누락 |

> 요약: 이 문제는 RPA 기능보다 자동화 후보 선정과 운영 통제 기준을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: RPA는 반복 업무를 소프트웨어 봇으로 자동화하는 기술이다.
- 배경: 레거시 시스템, API 부재, 엑셀·웹 포털 혼재 환경에서는 화면 기반 자동화가 단기 통합 수단이 될 수 있다.
- 필요성: 대상 업무, 예외 처리, 계정 권한, 실행 로그 기준을 정해 봇 장애와 감사 리스크를 통제해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
업무 규칙 -> Bot Script -> Orchestrator/Scheduler -> Target System
          -> Credential Vault -> Log/Exception Queue -> Operator Review
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 봇 스크립트 | 화면 조작, 입력, 조회, 파일 처리 수행 | UI 변경 영향 큼 |
| Orchestrator | 배포, 스케줄, 큐, 실행 상태 관리 | 중앙 운영 필수 |
| Credential Vault | 계정·비밀번호 보관 | 계정 공유 금지 |
| 예외 큐 | 실패 건 분류와 담당자 처리 | SLA와 재처리 기준 필요 |

> 요약: RPA는 봇 실행보다 Orchestrator, 자격증명, 예외 큐가 운영 품질을 좌우한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
업무 선정 -> 프로세스 기록 -> 봇 개발/테스트 -> 스케줄 실행
-> 결과 검증 -> 예외 큐 등록 -> 로그 감사
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 자동화 후보 선정 | 월 처리 1,000건, 예외율 10% 이하 |
| 2 | 봇 개발과 테스트 | 테스트 케이스 30건 이상 |
| 3 | 운영 실행 | 성공률 98% 이상, 재시도 3회 제한 |
| 4 | 예외·감사 | 실패 사유 코드화, 로그 1년 보관 |

> 요약: RPA는 업무 선정부터 예외 처리까지 폐쇄 루프로 운영해야 한다.

## Ⅳ. 특징

| 구분 | 수작업 처리 | RPA 적용 | 판단 포인트 |
|:---|:---|:---|:---|
| 처리 방식 | 담당자 화면 조작 | 봇이 동일 절차 수행 | 규칙 기반 업무 |
| 시스템 변경 | 없음 | 대상 시스템 변경 없음 | API 부재 환경 |
| 통제 | 사람 기록 의존 | 실행 로그·감사 추적 | 계정·권한 관리 |
| 한계 | 인력 의존 | UI 변경 시 실패 | UI 변경 빈도 월 1회 이하 |

> 요약: RPA는 시스템 변경 없이 자동화할 수 있지만 UI 변경과 예외율을 기준으로 적용 여부를 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 후보 선정: 반복성 높고 예외율 10% 이하이며 월 1,000건 이상 처리되는 업무를 우선 선정
2. 운영 통제: Bot 전용 계정, Credential Vault, Orchestrator 로그, 권한 분리 기준 적용
3. 전환 관리: UI 변경 잦은 업무와 핵심 거래 업무는 API 통합 전환 후보로 등록하고 분기별 재평가

**결론 (2줄):**
- 기술사 판단: 단기 반복 업무는 RPA, 장기 핵심 프로세스는 API·BPM 기반 통합으로 전환함
- 향후 방향: RPA는 OCR, NLP, LLM 기반 예외 분류와 결합해 지능형 프로세스 자동화로 확장됨
