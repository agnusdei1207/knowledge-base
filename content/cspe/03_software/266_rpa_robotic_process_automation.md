## Ⅰ. 개요
- **정의**: 소프트웨어 로봇이 사람의 반복적 업무 조작(클릭·입력·복사)을 규칙 기반으로 자동 수행하는 기술
- **배경/필요성**: 레거시 시스템 간 API 연동이 불가한 업무에서 수작업 비용과 오류가 지속적으로 발생함
- **비유**: 정해진 매뉴얼대로 화면을 조작하는 가상의 사무 보조원과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 업무 자동화 기술 이해 | Attended/Unattended 구분 | 단순 매크로와의 차이 명시 |

> 요약: RPA는 규칙 기반 소프트웨어 로봇으로 반복 업무를 자동화하여 수작업 비용과 오류를 감소시키는 기술임

## Ⅱ. 구성요소
```text
[Business Process] --녹화/설계--> [Bot Designer]
                                      |
                     +----------------+----------------+
                     |                |                |
                     v                v                v
               [Bot Runner]    [Orchestrator]    [Analytics]
               (Attended/       (스케줄링/        (실행로그/
                Unattended)      모니터링)          KPI)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Bot Designer | 업무 흐름을 녹화·편집하여 자동화 스크립트를 생성함 | 업무 매뉴얼 작성기 |
| Bot Runner | 설계된 시나리오를 실행하는 소프트웨어 로봇(Attended: 사용자 협업, Unattended: 독립 실행) | 매뉴얼대로 움직이는 직원 |
| Orchestrator | 다수 봇의 스케줄링·모니터링·자원 배분을 관리함 | 작업 배정 관리자 |

> 요약: 설계-실행-관리 3개 계층이 업무 자동화 생명주기를 구성함

## Ⅲ. 절차
```text
업무 분석 --> 시나리오 설계 --> 봇 실행 --> 모니터링/최적화
    |              |              |              |
    v              v              v              v
  대상선별      플로우녹화     스케줄실행    예외처리개선
```
- 1단계: 자동화 대상 업무를 식별하고 ROI 기준으로 우선순위를 선정함
- 2단계: Bot Designer에서 업무 플로우를 녹화·편집하여 시나리오를 설계함
- 3단계: Orchestrator가 스케줄에 따라 봇을 할당하고 실행함
- 4단계: 실행 로그를 분석하여 예외 처리를 보완하고 시나리오를 최적화함

> 요약: 분석-설계-실행-최적화 4단계 주기로 RPA를 운영함

## Ⅳ. 문제점
- 취약한 UI 의존: 화면 요소 변경 시 봇이 동작 불능에 빠짐 — 유지보수 비용이 증가함
- 예외 처리 한계: 규칙에 없는 상황 발생 시 봇이 중단됨 — 수작업 개입이 필요함
- 거버넌스 부재: 봇 수 증가 시 관리 체계가 미흡함 — 섀도우 RPA로 보안 위험이 확대됨

> 요약: UI 의존·예외 한계·거버넌스 부재가 RPA 확산의 주요 장애 요인임

## Ⅴ. 개선방안
1. 단기: API 기반 연동을 우선하고 UI 의존도를 최소화하는 하이브리드 설계 적용
2. 중기: AI/ML을 결합한 Intelligent Automation으로 비정형 예외를 자동 처리
3. 장기: CoE(Center of Excellence) 기반 RPA 거버넌스 프레임워크를 수립

> 요약: API 우선-지능형 자동화-거버넌스 체계 순으로 RPA를 고도화할 필요

## Ⅵ. 전망
- 발전 방향: LLM과 결합하여 비정형 문서 처리까지 포괄하는 Agentic Automation으로 진화함
- 기술사적 판단: 단순 RPA에서 AI 에이전트 기반 HyperAutomation으로 패러다임이 전환될 것임
- 기술사 제언: 자동화 대상 선정 기준과 CoE 운영 모델을 사전에 수립할 필요
