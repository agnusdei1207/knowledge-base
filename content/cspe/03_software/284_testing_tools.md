## Ⅰ. 개요
- 정의: 테스트 수행의 효율성을 높이기 위해 자동화, 관리, 분석 기능을 제공하는 SW
- 배경: 복잡해지는 시스템과 잦은 배포 주기 대응을 위해 수동 테스트의 한계 극복 필요
- 출제 의도: 단위 테스트(JUnit)와 UI 자동화(Selenium) 도구의 특징 및 활용 이해

## Ⅱ. 구성요소
- 구조도
  [Unit Level] -> [JUnit/xUnit] : Logic, Class 검증
  [UI/System Level] -> [Selenium] : Browser, Flow 검증

- 구성요소 표
| 도구 | 대상 | 특징 |
| :--- | :--- | :--- |
| JUnit | Java 단위 기능 | Assertion 기반, CI/CD 연동 필수 |
| Selenium | 웹 브라우저 UI | 다중 브라우저 지원, 스크립트 기반 자동화 |
| Postman | API 인터페이스 | HTTP 요청/응답 검증, 컬렉션 관리 |
> 요약: 테스트 레벨에 최적화된 도구 선택으로 검증 속도와 정확도 향상

## Ⅲ. 절차
- 흐름도
  도구 선정 -> 스크립트 작성 -> 자동 실행 -> 결과 분석/리포팅
- 4단계 설명
1. 도구 선정: 대상 플랫폼(Web, App, API) 및 팀 기술 역량에 맞는 도구 결정
2. 스크립트 작성: 테스트 시나리오를 코드로 구현 (Page Object Model 등 패턴 활용)
3. 자동 실행: CI/CD 파이프라인과 연동하여 코드 커밋 시마다 자동으로 테스트 트리거
4. 결과 분석: 대시보드를 통해 성공/실패 여부를 확인하고 실패 원인 분석 및 수정
> 요약: 자동화된 피드백 루프를 통해 품질 저하를 즉각적으로 감지

## Ⅳ. 문제점
- UI 변경 시 Selenium 스크립트가 쉽게 깨지는 등 자동화 코드 유지보수 비용 과다
- 모든 테스트를 자동화하려는 과욕으로 인한 초기 구축 비용 및 프로젝트 지연 발생

## Ⅴ. 개선방안
- UI 변경에 강인한 Selector 전략 수립 및 핵심 로직 중심의 점진적 자동화
- 테스트 자동화 자산에 대한 정기적 리팩토링 및 테스트 피라미드 원칙 준수

## Ⅵ. 전망
- Self-healing 기능을 갖춘 AI 기반 테스트 자동화 도구(Applitools 등) 확산
- CSF: 도구 도입보다 중요한 것은 테스트 가능한 아키텍처 설계 및 문화 조성
