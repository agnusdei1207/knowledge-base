## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 보조기억장치에 데이터를 저장하고 관리하기 위한 논리적 구조 및 방법 |
| 필요성 | 데이터 영구 저장, 계층적 관리, 보안/권한 제어 및 효율적 탐색 |
| 출제 의도 | 디렉터리 구조(Tree, DAG), 할당 기법(Linked, Indexed), 저널링 이해 |

## Ⅱ. 구성요소
```text
[ Boot Block ] [ Super Block ] [ Inode Table ] [ Data Blocks ]
       |               |               |               |
   (부팅정보)     (FS 메타데이터)   (파일 속성/포인터)   (실제 데이터)
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| i-node | 유닉스 계열 FS의 파일 메타데이터 저장 구조 | 책의 색인(Index) |
| 디렉터리 | 파일 이름을 i-node 번호와 매핑하는 특수 파일 | 폴더/서류함 |
| VFS | 서로 다른 FS를 동일한 인터페이스로 접근케 함 | 공용 어댑터 |
> 요약: i-node는 파일의 속성을, 데이터 블록은 실제 내용을 담음.

## Ⅲ. 절차
```text
Path Look-up -> Inode Check -> Access Control -> Block Allocation -> I/O
      |               |                |                |
(Root/Dir Scan) (Find Metadata) (Check Perm) (Link to Data)
```
1. 경로 탐색: 루트부터 파일명에 해당하는 i-node 번호를 단계적으로 추적.
2. 메타데이터 로드: 해당 i-node 정보를 메모리에 적재하여 위치/크기 확인.
3. 권한 검증: 프로세스 소유자와 파일 권한(RWX)을 대조하여 승인.
4. 데이터 접근: 인덱스 블록 등을 통해 실제 데이터가 저장된 물리 블록 I/O.
> 요약: 계층적 디렉터리 탐색을 통해 최종 물리 블록에 도달하는 프로세스임.

## Ⅳ. 문제점
- 불의의 전원 차단 시 메타데이터와 데이터 간 불일치(Inconsistency) 발생.
- 잦은 파일 생성/삭제로 인한 디스크 단편화 및 탐색 속도 저하.

## Ⅴ. 개선방안
- 저널링(Journaling) 기법 도입으로 변경 사항 선기록 후 비정상 종료 시 복구.
- B-Tree 또는 Extent 기반 할당을 통해 대용량 파일 탐색 성능 최적화.

## Ⅵ. 전망
- 분산 파일 시스템: 클라우드 환경에서 PB급 데이터를 관리하는 HDFS, Ceph 확산.
- 데이터 중복 제거(Deduplication): 스토리지 효율화를 위한 블록 단위 중복 제거 기본 탑재.
