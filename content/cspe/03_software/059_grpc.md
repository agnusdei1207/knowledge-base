## Ⅰ. 개요
- 정의: 구글이 개발한 고성능 RPC 프레임워크로 HTTP/2 기반의 이진 직렬화 통신 수행.
- 출제 의도: MSA 환경에서 서비스 간 통신 성능 극대화 및 강력한 타입 체크를 위한 기술 역량 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Client (.proto) ] --- (Stub) ---> [ gRPC Runtime ]
                                          | (HTTP/2, Binary)
  [ Server (.proto) ] <--- (Skeleton) -- [ gRPC Runtime ]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Protobuf | IDL(인터페이스 정의 언어)이자 이진 직렬화 포맷 | 압축된 공용 양식 |
| Stub | 클라이언트에서 서버 메서드를 로컬 함수처럼 호출하는 대행자 | 아바타/분신 |
| HTTP/2 | 멀티플렉싱, 헤더 압축을 통해 전송 효율을 높인 기반 프로토콜 | 고속도로 |
> 요약: 텍스트 기반 JSON보다 작고 빠른 이진 데이터를 사용해 통신 효율 극대화함.

## Ⅲ. 절차
- ASCII 흐름도
  [.proto 작성] -> [코드 생성] -> [서버 로직 구현] -> [클라이언트 호출]
- 4단계 설명
1. `.proto` 파일에 서비스 명세와 데이터 메시지 타입을 엄격히 정의함.
2. `protoc` 컴파일러를 통해 다양한 언어별 클라이언트/서버 코드 자동 생성함.
3. 생성된 코드를 기반으로 서버 측 비즈니스 로직을 구체화함.
4. 클라이언트는 Stub을 통해 원격 서버의 함수를 직접 호출하듯 사용함.
> 요약: 언어 독립적인 인터페이스 정의를 통해 폴리글랏 MSA 구현 지원함.

## Ⅳ. 문제점
- 브라우저 제약: 웹 브라우저에서 gRPC 직접 호출 시 HTTP/2 및 프레임 제어로 인해 지원 제한됨.
- 가독성 저하: 데이터가 이진 형태라 디버깅 시 사람이 직접 내용을 확인하기 어려움.

## Ⅴ. 개선방안
- gRPC-Web: 프록시(Envoy)를 중간에 두어 브라우저의 HTTP/1.1 요청을 gRPC로 변환함.
- 반사(Reflection): 서버에 gRPC Reflection 기능을 활성화하여 도구(Postman 등)로 디버깅함.

## Ⅵ. 전망
- 클라우드 네이티브 인프라(K8s 내부 통신 등)의 표준 통신 프로토콜로 자리 잡음.
- 대규모 트래픽 처리가 필요한 데이터 파이프라인 및 백엔드 간 통신의 핵심 기술로 지속 활용됨.
- 모바일 앱의 응답 속도 개선을 위해 REST 대신 gRPC를 도입하는 사례가 늘어날 것임.
