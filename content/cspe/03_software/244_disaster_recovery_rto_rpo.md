## Ⅰ. 개요
- **정의**: 재해 발생 시 시스템 복구 목표를 시간(RTO)과 데이터 손실(RPO) 기준으로 정의하는 체계임
- **배경/필요성**: 복구 목표 없이 DR을 수행하면 과도한 비용이 투입되거나 복구 수준이 불충분해지므로 정량 기준이 필요함
- **비유**: RTO는 "언제까지 병원에 도착해야 하는가", RPO는 "어디까지의 기억을 살릴 수 있는가"에 해당함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| RTO·RPO 개념 구분과 DR 전략 매핑 | RTO=복구 시간, RPO=허용 데이터 손실 | 두 지표를 혼동하지 않고 DR 등급별 전략과 연결할 것 |

> 요약: RTO와 RPO로 복구 목표를 정량화하여 DR 전략의 수준과 비용을 결정함

## Ⅱ. 구성요소
```text
   RPO                    RTO
<---|---------X-----------|--->
 데이터 손실   재해 발생   서비스 복구
  허용 구간    시점        목표 시점
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| RPO | 재해 시 허용 가능한 최대 데이터 손실 시간임 | 자동 저장 주기 |
| RTO | 재해 발생부터 서비스 복구까지 허용 최대 시간임 | 구급차 도착 시간 |
| DR Tier | RPO·RTO 조합에 따른 복구 전략 등급(Hot/Warm/Cold)임 | 보험 등급 |
| BIA | 업무 영향 분석으로 시스템별 RPO·RTO를 도출하는 과정임 | 손해 사정 |

> 요약: BIA로 RPO·RTO를 도출하고 DR Tier에 매핑하여 복구 전략을 결정함

## Ⅲ. 절차
```text
BIA 수행 --> RPO/RTO 설정 --> DR 전략 선택 --> DR 테스트/검증
```
- 1단계: BIA 수행 — 업무별 중단 영향을 분석하여 복구 우선순위 결정
- 2단계: RPO/RTO 설정 — 각 시스템의 허용 손실·복구 시간 목표를 정량 수립
- 3단계: DR 전략 선택 — Hot(실시간 복제), Warm(주기적 복제), Cold(백업 복원) 중 선택
- 4단계: DR 테스트 — 정기적 모의 전환(Failover Drill)으로 실제 RTO·RPO 달성 여부 검증

> 요약: BIA → 목표 설정 → 전략 선택 → 테스트 순으로 DR 체계를 수립함

## Ⅳ. 문제점
- 과도한 비용: 모든 시스템에 Hot-Site 수준 적용 시 인프라·운영 비용이 급증함
- 목표 미달: DR 테스트 미흡으로 실제 재해 시 설정된 RTO·RPO를 충족하지 못함
- 데이터 정합성 결여: 비동기 복제 환경에서 RPO 내 데이터라도 트랜잭션 정합성이 깨질 수 있음

> 요약: 비용 과다, 테스트 부족, 데이터 정합성 문제가 주요 과제임

## Ⅴ. 개선방안
1. 단기: BIA 기반 시스템 등급화로 Hot/Warm/Cold 전략을 차등 적용하여 비용 최적화
2. 중기: 자동화된 DR Drill을 분기별 시행하고 RTO·RPO 달성률을 정량 측정
3. 장기: CDC(Change Data Capture) 기반 실시간 복제로 트랜잭션 정합성 보장

> 요약: 등급 차등, 정기 테스트, 실시간 복제를 통해 DR 실효성을 확보함

## Ⅵ. 전망
- 발전 방향: DRaaS(DR as a Service) 확산으로 클라우드 기반 자동 복구가 보편화될 전망임
- 기술사적 판단: HA(245 참조)와 DR을 통합 설계하여 장애·재해 모두를 포괄하는 것이 바람직함
- 기술사 제언: RPO=0, RTO≒0을 요구하는 핵심 시스템에는 Active-Active 구성 검토가 필요함
