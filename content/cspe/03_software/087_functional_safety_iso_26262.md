# 📖 【암기용】 개념 완전 이해

> 목적: ISO 26262와 ASIL을 자동차 E/E 시스템의 기능 안전 표준과 위험 등급 체계로 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: ISO 26262는 자동차 전기·전자(E/E) 시스템의 **기능 안전(Functional Safety)**을 다루는 국제표준이며, ASIL(Automotive Safety Integrity Level)은 그 안에서 오작동 위험의 크기를 등급화한 **위험 등급**이다.
- **왜 필요한가**: 제동·조향·배터리 제어 SW의 오작동은 곧바로 인명 사고로 이어진다. "테스트를 많이 했다"만으로는 안전을 증명할 수 없어, 위험을 등급으로 나눠 그 등급에 맞는 개발·검증 강도를 강제하는 표준이 필요하다.
- **핵심 직관**: 병원 응급실이 환자 중증도(트리아지)에 따라 처치 우선순위와 검사 강도를 달리하듯, ISO 26262도 차량 기능의 위험도(ASIL)에 따라 요구되는 검증 강도를 달리한다 — 와이퍼 오작동과 브레이크 오작동은 같은 급으로 다루지 않는다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 기능 안전(Functional Safety) | 시스템/SW의 오작동으로 인한 위험을 관리하는 것(이 개념의 상위 키워드) | 의료기기가 오작동해서 환자를 다치게 하지 않도록 관리하는 것 |
| HARA (Hazard Analysis and Risk Assessment) | 위험원을 찾아 위험도를 평가하는 절차 | 응급실 트리아지(중증도 분류) 절차 |
| Severity(S, S0~S3) | 사고가 나면 얼마나 심각한 피해인가 | 부상의 경중 |
| Exposure(E, E0~E4) | 그 위험 상황에 얼마나 자주 노출되는가 | 위험 상황을 겪을 빈도 |
| Controllability(C, C0~C3) | 운전자가 사고를 피할 수 있는 정도 | 환자 스스로 상황을 통제할 수 있는지 |
| ASIL (A~D, QM) | S·E·C 조합으로 정해지는 위험 등급, D가 최고 | 응급 등급(경증~최중증) |
| Safety Goal | ASIL이 매겨진 hazard를 없애기 위한 최상위 안전 목표 | 치료 목표 |
| FSC / TSC | 안전목표를 기능 수준(FSC)·기술 수준(TSC) 요구사항으로 구체화한 것 | 치료 계획 → 처방 세부사항 |
| V-model | 설계 단계와 대응하는 검증 단계를 짝짓는 개발 프로세스 모형 | 처방 각 단계마다 대응하는 검사 단계 |
| Safety Case | ASIL 요구를 충족했다는 증거를 모은 문서 | 진료 완료 후 치료 근거 기록 |

## 깊이 이해

### 왜 ISO 26262가 필요했나 (배경)
- 차량이 SDV(Software Defined Vehicle)로 전환되며 센서·ECU·OTA·AI 기능이 급격히 늘었고, 기계적 결함이 아니라 SW 결함이 직접 사고로 이어지는 비중이 커졌다. ISO 26262는 산업 전반의 기능 안전 표준인 IEC 61508을 자동차 도메인에 맞게 특화해 2011년 제정됐다.

### HARA로 ASIL을 정하는 원리 — S·E·C 조합
- HARA는 hazard(위험원) 각각에 대해 세 가지를 평가한다. ① Severity(피해가 나면 얼마나 심각한가, S0 무해~S3 생명 위협) ② Exposure(그 상황에 얼마나 자주 노출되는가, E0 극히 드묾~E4 상시) ③ Controllability(운전자가 상황을 얼마나 통제할 수 있는가, C0 통제 가능~C3 통제 거의 불가능). 세 값이 모두 클수록(심각하고, 자주 일어나고, 피할 수 없을수록) ASIL이 높아진다.
- **워크드 예제**: 고속도로 주행 중 조향 보조 시스템이 갑자기 반대 방향으로 조향을 거는 오작동을 생각해보자. 피해는 치명적이므로 S3, 고속도로 주행은 상시 상황이므로 E4, 순간적으로 반대 조향이 걸리면 운전자가 피하기 거의 불가능하므로 C3다. 이 조합은 표준의 ASIL 결정 규칙에서 최고 등급인 **ASIL D**로 이어진다.
- 반대로, 저속 주차 시 후방 와이퍼가 한 박자 늦게 작동하는 결함은 S1(경미), E2(가끔), C1(운전자가 쉽게 인지·대응 가능) 수준이라 **QM(Quality Management)** — 별도의 ISO 26262 안전 활동 없이 일반 품질관리로 충분한 등급 — 으로 분류될 수 있다.

### ASIL 등급이 개발 강도를 어떻게 바꾸는가
- 등급은 QM < A < B < C < D 순으로 올라가며, 등급이 높을수록 다음이 강해진다.
  - **독립성**: ASIL C/D는 설계자와 검증자가 조직적으로 독립되어야 한다(같은 사람이 만들고 스스로 검증하지 않음).
  - **테스트 커버리지**: MC/DC(Modified Condition/Decision Coverage) 같은 강한 구조 커버리지 기준이 ASIL C/D에서 요구된다.
  - **진단 커버리지**: 하드웨어 고장을 스스로 감지하는 능력(단일점 고장 지표 SPFM 등)에 대해 ASIL D는 매우 높은 목표치를 요구한다.
  - **도구 검증(Tool Qualification)**: 개발에 쓰는 컴파일러·정적분석 도구 자체도 신뢰할 수 있음을 별도로 입증해야 한다.

### V-model 검증 구조
- 좌측(요구사항 정의 → 아키텍처 설계 → 상세설계 → 구현)과 우측(단위테스트 → 통합테스트 → 시스템테스트 → 차량 레벨 검증)을 대칭으로 짝짓는다. 상세설계에서 정한 내용은 반드시 대응하는 통합테스트로, 요구사항은 시스템테스트로 검증되도록 구조화해, 어느 설계 산출물도 검증 없이 넘어가지 못하게 한다.

### 흔한 오해와 주의점
- ISO 26262는 자동차 SW 품질 전체를 다루는 표준이 아니라, **오작동(malfunction)으로 인한 안전 위험**만 다루는 기능 안전 표준이다. 시스템이 의도한 대로 정확히 동작하는데도 그 인식 능력의 한계 때문에 위험해지는 경우(예: 카메라가 인식하기 어려운 조건에서 보행자를 놓치는 것)는 별도 표준인 SOTIF(ISO 21448, Safety Of The Intended Functionality)가 다룬다 — 둘은 서로 보완 관계다.
- ASIL D는 "위험하다"는 정성적 표현이 아니라 S·E·C 평가와 표준의 결정 규칙을 근거로 산정된 등급이며, 등급마다 요구되는 구체적 개발·검증 활동이 표준에 명시돼 있다.

## 연결 개념
- HARA — ASIL을 산정하는 절차 자체(위 표에도 있지만, ISO 26262 생명주기의 핵심 입력 단계로 별도 학습 필요)
- SOTIF(ISO 21448) — 오작동이 아니라 의도된 기능의 성능 한계로 인한 위험을 다루는 보완 표준
- GAMAB·ALARP(086) — "잔여위험을 어느 수준까지 낮출 것인가"라는 안전 원칙을 자동차 도메인에서 ASIL이라는 구체적 등급 체계로 구현한 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: ISO 26262 답안은 ASIL 산정, 안전요구사항 전개, V-model 검증, safety case를 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO 26262는 자동차 E/E 시스템의 기능 안전을 HARA, ASIL, 안전요구사항, 검증 증거로 관리하는 표준이다.
> 2. **가치**: 사고 위험을 Severity, Exposure, Controllability로 계량해 ASIL A~D에 맞는 개발·검증 강도를 적용한다.
> 3. **판단 포인트**: ASIL 등급이 높을수록 독립성, 추적성, 진단 커버리지, 테스트 증거 요구가 커지므로 개발 프로세스와 도구 검증이 필요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기능 안전 표준 이해 확인 | ISO 26262, HARA, ASIL A~D | 일반 보안·품질 인증으로 설명하지 않음 |
| 자동차 SW 적용 역량 확인 | 안전목표, FSC, TSC, V-model 검증 | ASIL 산정 없이 테스트만 나열하지 않음 |
| 잔여위험 판단 확인 | safety case, 독립 검증, tool qualification | ASIL D를 단순 고위험 문구로만 쓰지 않음 |
> 요약: ISO 26262 문제는 위험도 산정에서 안전 요구 전개와 증거 기반 검증까지의 추적성을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 자동차 기능 안전 표준
- 배경: 차량 제어 SW는 오작동 시 인명 피해로 이어질 수 있어 위험원 식별, ASIL 등급, 안전 요구사항 추적이 필요하다.
- 필요성: ISO 26262는 HARA, ASIL A~D, safety mechanism, verification evidence로 SDV·OTA·ADAS 변경을 안전 lifecycle 안에서 통제한다.

## Ⅱ. 구조 및 구성요소

```text
Item Definition -> HARA -> ASIL Determination
-> Safety Goal -> FSC -> TSC -> HW/SW Safety Requirement
-> Verification/Validation -> Safety Case
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| Item Definition | 대상 기능과 경계 설정 | 운전 시나리오, 인터페이스 |
| HARA/ASIL | 위험 평가와 등급 산정 | S, E, C 조합 |
| Safety Requirement | 안전목표를 설계 요구로 전개 | FSC, TSC, SW 요구 |
| Safety Case | 안전 달성 증거 통합 | 테스트, 분석, 리뷰 증거 |
> 요약: ISO 26262는 item 경계에서 ASIL을 정하고 안전 요구와 검증 증거로 전개한다.

## Ⅲ. 동작원리 및 흐름도

```text
차량 기능 분석 -> hazard 도출 -> S/E/C 평가
-> ASIL 산정 -> safety goal 설정 -> SW safety requirement 전개
-> V-model 검증 -> safety case 승인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 대상 기능과 운용 시나리오 식별 | 시나리오 coverage 100% |
| 2 | HARA 수행과 ASIL 결정 | S/E/C 평가 근거 |
| 3 | 안전목표와 요구사항 전개 | 양방향 추적성 100% |
| 4 | 설계·구현·검증 수행 | MC/DC, fault injection |
| 5 | 안전 증거 통합과 승인 | safety case 완결성 |
> 요약: ISO 26262는 HARA로 ASIL을 정하고 V-model 검증 증거로 안전목표 달성을 입증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Item Definition 단계에서 기능 경계, 운전 시나리오, 외부 인터페이스를 확정하고 HARA 워크숍을 수행함.
2. ASIL 등급별로 코딩규칙, MC/DC, fault injection, 독립 리뷰 수준을 차등 적용함.
3. OTA 변경마다 safety impact analysis를 수행하고 안전 요구-테스트-safety case 링크를 갱신함.

**결론 (2줄):**
- 기술사 판단: 인명 피해 가능 차량 기능은 ISO 26262와 ASIL 기반 프로세스를 적용하고, 인포테인먼트 기능은 품질·보안 기준을 별도 적용함.
- 향후 방향: SDV 시대 기능 안전은 SOTIF, 사이버보안, OTA 운영 안전과 통합된 차량 SW 거버넌스로 확장됨.
