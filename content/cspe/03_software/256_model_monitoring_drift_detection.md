## Ⅰ. 개요
- **정의**: 운영 중 모델의 입력 분포·예측 성능 변화를 감지하고 대응하는 체계임
- **배경/필요성**: 학습 시점과 운영 시점의 데이터 분포 차이가 누적되면 모델 정확도가 점진적으로 하락함
- **비유**: 자동차 계기판처럼 주행 중 엔진 상태를 실시간 감시하여 고장 전 경고하는 체계임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 모델 성능 저하 원인 분석·대응 | Data Drift vs Concept Drift 구분 | 두 드리프트 미구분 시 감점 |

> 요약: 운영 모델의 성능 저하를 조기 감지하여 재학습 트리거를 제공하는 체계임

## Ⅱ. 구성요소
```text
Serving Input --> Data Collector --> Drift Detector
                                          |
                        +-----------------+-----------------+
                        |                 |                 |
                  Data Drift        Concept Drift      Performance
                  Monitor            Monitor            Monitor
                        |                 |                 |
                        +--------+--------+---------+-------+
                                 |                  |
                              Alerter          Retrain Trigger
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Data Drift Monitor | 입력 피처 분포 변화 탐지(PSI, KS-test 등) | 원재료 품질 변화 감지 |
| Concept Drift Monitor | 입력-출력 관계 변화 탐지(정답 레이블 필요) | 시장 트렌드 변동 감시 |
| Performance Monitor | 정확도·지연시간·처리량 등 서비스 지표 추적 | 엔진 출력 계기판 |
| Alerter | 임곗값 초과 시 알림 발송(Slack, PagerDuty 등) | 화재 경보기 |
| Retrain Trigger | 드리프트 감지 시 재학습 파이프라인 자동 기동 | 자동 정비 호출 |

> 요약: 데이터·컨셉·성능 3종 모니터와 알림·재학습 트리거로 구성됨

## Ⅲ. 절차
```text
Collect Serving Data --> Compute Statistics --> Detect Drift --> Act
```
- 1단계: 서빙 데이터 수집 — 추론 요청·응답·Ground Truth를 로그로 적재
- 2단계: 통계 산출 — 피처 분포 통계량·모델 성능 지표를 주기적으로 계산
- 3단계: 드리프트 탐지 — PSI·KS-test 등 통계 검정으로 분포 변화 판별
- 4단계: 대응 — 알림 발송, 자동 재학습 트리거 또는 모델 롤백 실행

> 요약: 수집 → 통계 → 탐지 → 대응의 4단계로 드리프트에 대처함

## Ⅳ. 문제점
- Ground Truth 지연: 정답 레이블 확보까지 시간이 걸려 Concept Drift 탐지가 지연됨
- 오탐/미탐 균형: 임곗값이 민감하면 오탐 과다, 둔감하면 실제 드리프트를 놓침
- 다변량 복잡도: 고차원 피처 공간에서 단변량 검정만으로는 상호작용 변화를 포착 불가함

> 요약: 레이블 지연·임곗값 설정·고차원 복잡도가 주요 과제임

## Ⅴ. 개선방안
1. 단기: Proxy 지표(예측 확신도 하락 등)로 레이블 없이 간접 Concept Drift 탐지
2. 중기: 적응형 임곗값(이동 평균·Bayesian 기법)으로 오탐/미탐 균형 자동 조정
3. 장기: 다변량 드리프트 검정(MMD, Autoencoder 기반)으로 고차원 분포 변화 탐지

> 요약: 프록시 지표·적응형 임곗값·다변량 검정으로 탐지 정확도를 높임

## Ⅵ. 전망
- 발전 방향: 드리프트 원인 자동 진단(Root Cause Analysis)과 자동 재학습 연계가 확산됨
- 기술사적 판단: 모델 운영 신뢰성 확보의 핵심 요소로 규제 감사 요건에 포함되는 추세임
- 기술사 제언: 모니터링 지표 설계를 모델 개발 단계부터 함께 수행해야 함
