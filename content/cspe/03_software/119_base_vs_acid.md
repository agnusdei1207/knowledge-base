## 미리 알고가기

- ACID는 전부 성공하거나 전부 실패해야 하는 업무 데이터를 안전하게 처리하는 트랜잭션 원칙임
- BASE는 일부 불일치를 잠시 허용해도 서비스가 계속 열려 있어야 하는 분산 처리 방식임
- 최종 일관성은 잠시 값이 달라도 시간이 지나면 결국 같은 상태로 맞춰지는 성질임

- 보상 트랜잭션은 이미 완료된 분산 단계의 효과를 반대 업무로 상쇄해 최종 상태를 맞추는 처리임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- ACID와 BASE는 정확성·가용성·실패 복구 방식을 핵심 축으로 설명함
- 비교표는 ACID와 BASE의 우선 가치·실패 처리·대표 업무를 대비함
- 거래·피드 시스템은 복구 실패 건수·불일치 지속 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: ACID는 트랜잭션의 정확성과 복구를 보장하고, BASE는 가용성과 확장성을 위해 일시적 불일치를 허용하는 데이터 처리 원칙임
- **배경/필요성**: 업무별 정확성·응답성·확장성 요구가 다르므로 거래 데이터와 분산 조회 데이터에 맞는 처리 원칙을 구분해야 함

### 쉽게 이해하기 (학습용)
- ACID는 거래를 한 번에 확정하고, BASE는 각 지점 기록을 먼저 받은 뒤 나중에 맞춤

## Ⅱ. 특징

- ACID는 오류와 동시성 상황에서도 데이터 신뢰성을 우선함
- BASE는 서비스 지속성과 확장성을 우선해 빠른 분산 처리를 얻기 쉬움
- ACID는 잠금과 동기화 비용이 커질 수 있음
- BASE는 사후 보정과 사용자 안내가 함께 설계돼야 함

### 쉽게 이해하기 (학습용)
- 즉시 정확성과 확장·가용성의 우선순위에 따라 실패를 되돌릴지 사후 보정할지 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | ACID | BASE |
|:---|:---|:---|
| 우선 가치 | 원자적 처리·무결성 제약·복구 | 가용성·확장성·사후 수렴 |
| 실패 처리 | 롤백과 복구 로그로 트랜잭션 원자성 유지 | 재시도·보상·병합으로 복제본 상태 수렴 |
| 대표 업무 | 원자적 커밋이 필요한 결제·주문·재고 | 일시 불일치를 허용하는 피드·알림·추천 |

> 요약: ACID는 원자적 트랜잭션과 무결성 제약을, BASE는 가용성과 복제본의 사후 수렴을 우선함.

### 쉽게 이해하기 (학습용)
- 결제·재고는 ACID, 피드·알림은 일시 차이를 허용하는 BASE가 잘 맞을 수 있음

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 처리 단위 | 한 번에 묶어 성공시킬 범위를 정함 |
| 동시성 제어 | 여러 요청의 읽기·쓰기 충돌을 통제함 |
| 실패 복구 | 중간 실패 시 되돌릴지, 나중에 보정할지 정함 |
| 일관성 정책 | 즉시 맞출지, 시간이 지나며 맞출지 정함 |

> 요약: 처리 단위와 동시성 제어가 데이터 변경 범위를 정하고 실패 복구와 일관성 정책이 오류 처리 방식을 결정함.

### 쉽게 이해하기 (학습용)
- 묶을 업무 범위, 동시 충돌, 실패 때 되돌림과 사본 맞춤 시간을 함께 정함

## Ⅴ. 원리 및 절차 흐름도

```text
ACID: [트랜잭션 시작] -> [검증·잠금] -> [커밋 또는 롤백]
BASE: [변경 수락] -> [비동기 전파] -> [재시도·병합·보상] -> [수렴]
```

1. 원자적 확정이 필요한 업무와 일시 불일치를 허용할 업무를 분류함
2. ACID는 트랜잭션 경계·격리·로그 복구를, BASE는 전파·재시도·충돌 해결을 설계함
3. 중간 실패를 롤백 또는 보상 처리하고 중복 요청의 멱등성을 보장함
4. 복구 실패 건수·불일치 지속 시간·처리 지연으로 정책을 검증함

> 요약: 업무 정확성 요구에 따라 즉시 커밋·롤백 또는 비동기 전파·사후 수렴 경로를 선택함.

### 쉽게 이해하기 (학습용)
- 거래 전체를 즉시 확정하거나 지점별 기록을 먼저 받고 나중에 장부를 맞추는 두 흐름임

## Ⅵ. 실무 사례

1. 결제 DB는 ACID 트랜잭션을 적용하고 잠금 대기 시간·복구 실패 건수를 확인함
2. 알림 서비스는 BASE의 재시도·보상 처리를 적용하고 불일치 지속 시간·재처리 성공률을 확인함

### 쉽게 이해하기 (학습용)
- 결제 원장은 즉시 확정하고 알림·추천은 재시도와 보상으로 나중에 맞출 수 있음

## Ⅶ. 결론

- ACID와 BASE는 업무의 정확성·가용성·확장성 요구에 따라 처리 원칙과 복구 방식을 선택함
- 두 모델을 제품 이름으로 단정하지 말고 업무 단위별 원자성·허용 지연·보상 가능성으로 선택해야 함

### 쉽게 이해하기 (학습용)
- 한 시스템에서도 돈은 즉시 맞추고 알림은 나중에 맞추는 식으로 업무별 선택이 가능함
