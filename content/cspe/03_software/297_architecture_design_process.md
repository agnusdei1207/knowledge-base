## Ⅰ. 개요
- 정의: 비즈니스 요구사항을 기반으로 소프트웨어의 구조적 기틀을 수립하는 체계적 과정임
- 배경: 대규모 시스템의 복잡성 관리와 품질 속성 만족을 위한 기술적 의사결정 필요
- 출제 의도: 아키텍처 설계의 단계별 활동 및 품질 중심 설계 절차 이해도 평가

## Ⅱ. 구성요소
- ASCII 구조도
  [Input] -> [Design Cycle] -> [Output]
     |            |             |
   Reqs      View/Pattern    ADL/Spec
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 아키텍처 드라이버 | 설계를 결정짓는 핵심 요구사항 및 제약사항 | 핵심 엔진 사양 |
| 아키텍처 뷰(View) | 특정 관점(논리, 구현 등)에서 본 시스템 구조 | 층별 평면도 |
| 설계 후보 도출 | 품질 속성을 만족하는 대안 구조 탐색 | 설계안 A/B |
> 요약: 요구사항을 입력으로 받아 다각도의 뷰를 통해 최적의 구조를 도출함

## Ⅲ. 절차
- ASCII 흐름도
  Requirement -> Design -> Documentation -> Evaluation
- 4단계 설명
1. Requirement: 기능 및 품질 속성(QA), 제약 사항 등 설계 동인 식별함
2. Design: 구조적 패턴(Pattern) 적용 및 컴포넌트 간 상호작용 정의함
3. Documentation: 4+1 View 등을 활용하여 아키텍처를 가시화하고 기술함
4. Evaluation: ATAM, CBAM 등을 통해 품질 목표 달성 여부 검증함
> 요약: 요구사항 분석 후 패턴 적용, 문서화 및 정형 기법 평가를 거쳐 확정함

## Ⅳ. 문제점
- 원인이 명시된 문제/한계: 품질 속성 간의 충돌(Trade-off) 분석 미흡 시 아키텍처 왜곡 발생함

## Ⅴ. 개선방안
- Ⅳ의 문제에 대응하는 방안: 유틸리티 트리(Utility Tree) 기반 우선순위 결정 및 시나리오 평가함

## Ⅵ. 전망
- 발전 방향: 진화적 아키텍처(Evolutionary Architecture) 개념 도입 및 자동화 설계 도구 확산
- CSF: 비즈니스 가치와 기술적 타당성 간의 균형 잡힌 의사결정(Decision Making)이 핵심임
