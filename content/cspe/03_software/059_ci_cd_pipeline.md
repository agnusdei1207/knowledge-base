## 미리 알고가기

- CI는 작은 변경을 자주 통합해 빠르게 검증하는 활동임
- CD는 검증된 변경을 배포 가능한 상태나 실제 운영 배포까지 자동화하는 활동임
- 파이프라인은 빌드와 테스트와 배포 단계를 연결한 자동 흐름임

## Ⅰ. 개요

- **정의/개념**: CI/CD 파이프라인은 코드 변경이 저장소에 반영된 뒤 빌드와 테스트와 품질 검증과 배포 단계를 자동으로 통과해 운영 반영까지 이어지도록 구성한 소프트웨어 전달 자동화 체계임
- **배경/필요성**: 배포 빈도가 높아질수록 수동 검증과 수작업 배포는 오류와 지연을 키우므로, 변경을 빠르고 반복 가능하게 전달하는 자동 경로가 필요함

## Ⅱ. 특징

- 작은 변경을 빠르게 검증해 통합 리스크를 줄임
- 배포 프로세스의 재현성과 추적성을 높임
- 테스트 신뢰도와 환경 일관성이 낮으면 자동화가 오히려 불신을 키울 수 있음
- 보안과 품질 게이트를 파이프라인 안에 포함할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 배포 흐름 | CI/CD 파이프라인 |
|:---|:---|:---|
| 검증 방식 | 사람 중심 | 자동 단계 중심 |
| 장점 | 초기 도입 단순 | 빠른 피드백과 반복성 |
| 한계 | 오류와 지연 큼 | 초기 구축과 유지 비용 필요 |
| 적합 환경 | 소규모/저빈도 배포 | 빈번한 제품 배포 조직 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Source Trigger | 코드 변경을 감지해 파이프라인 실행을 시작하는 입구임 |
| Build and Test Stage | 컴파일과 단위 테스트와 정적 검사를 수행해 기본 품질을 걸러냄 |
| Quality Gate | 보안과 커버리지와 정책 위반 여부를 판단해 배포 허용 여부를 결정함 |
| Deployment Stage | 스테이징과 운영 환경에 동일 아티팩트를 승격 배포해 재현성을 유지함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드 변경      | --> | 빌드/테스트    | --> | 품질 게이트    | --> | 배포/승격      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드 변경**: 커밋이나 병합이 파이프라인을 시작함
2. **빌드 및 테스트**: 아티팩트를 만들고 핵심 검증을 수행함
3. **품질 게이트**: 실패 조건과 승인 조건을 통과 여부로 판단함
4. **배포 및 승격**: 동일 아티팩트를 환경별로 승격 배포함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 테스트가 느리거나 불안정하면 파이프라인 병목과 신뢰 저하가 동시에 발생할 수 있음
   - 해결방안: 테스트 계층 분리와 flaky 관리 체계를 적용하고 pipeline lead time과 flaky test rate로 검증함
2. 문제: 환경마다 설정과 아티팩트가 다르면 자동화돼도 배포 재현성이 깨질 수 있음
   - 해결방안: immutable artifact와 config 관리 표준을 적용하고 environment drift count와 deployment rollback rate로 검증함
3. 문제: 품질 게이트가 형식적이면 빠른 배포만 남고 실제 결함은 운영으로 빠져나갈 수 있음
   - 해결방안: defect 기반 게이트를 조정하고 defect escape rate와 gate effectiveness score로 검증함

## Ⅶ. 적용 사례

- 웹 서비스 개발팀에서는 CI/CD 파이프라인을 운영하고 확인 지표는 pipeline lead time과 deployment frequency임
- 보안 민감 서비스에서는 품질 게이트를 강화하고 확인 지표는 gate effectiveness score와 defect escape rate임
- 멀티환경 배포 조직에서는 immutable artifact를 적용하고 확인 지표는 environment drift count와 deployment rollback rate임

## Ⅷ. 결론

CI/CD의 진짜 가치는 자동 배포 버튼이 아니라 작은 변경을 믿고 자주 운영까지 전달할 수 있게 만드는 검증 체계에 있음.
