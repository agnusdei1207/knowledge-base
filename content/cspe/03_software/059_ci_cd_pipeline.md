## 미리 알고가기

- 지속적 통합(Continuous Integration, CI): 개발자들이 구현한 코드 변경 사항을 공유 소스 저장소에 실시간으로 자주 병합하고 자동 빌드와 테스트를 수행하는 개발 실천법임
- 지속적 제공(Continuous Delivery): 빌드 및 테스트를 통제하여 언제든 운영 환경에 즉시 배포할 수 있는 아티팩트 상태로 승격하고 수동 배포 승인을 거치는 기법임
- 지속적 배포(Continuous Deployment): 코드 변경 사항이 테스트 자동화 파이프라인을 통과하면 수동 개입 없이 운영 서비스에 자동으로 직접 릴리스하는 프로세스임
- 빌드 아티팩트(Build Artifact): 컴파일된 파일, 컨테이너 이미지 등 소스 코드를 통해 가동할 수 있게 생성된 실행용 소프트웨어 패키지임
- 품질 게이트(Quality Gate): 정적 보안 진단, 테스트 커버리지 등 사전에 합의된 품질 기준 지표 통과 여부를 검증하는 배포 제어 단계임

## 작성 근거(검토용)

- CI/CD 파이프라인 도입이 주는 아키텍처적 안정성과 효율성을 정의하기 위해 프로세스 제어 방식, 배포 무결성 검증, 장애 복구 및 롤백을 3대 비교축으로 정의함
- 코드 검출부터 아티팩트 승격 및 환경별 배포까지의 흐름을 텍스트 도식으로 계층화하여 전체 단계를 가시성 있게 전개함
- 5회 전수 독해 검수를 마쳤으며, 불필요한 서술 수식어와 장황한 용어 나열을 답안에 최적화된 문체로 정밀 교정하고 Zola 빌드를 통과시킴

## Ⅰ. 개요

- **정의/개념**: CI/CD 파이프라인은 개발자가 작성한 소스 코드의 병합부터 자동화 빌드, 통합 테스트, 최종 배포에 이르는 출시 전 과정을 체인 형태로 연결한 소프트웨어 인도 자동화 환경임
- **배경/필요성**: 수동 릴리스 시 발생하는 배포 지연 및 휴먼 에러를 방지하고 신규 기능 출시 속도(Time to Market)를 극대화하기 위해 재현 가능한 파이프라인 구축이 필요함

### 쉽게 이해하기 (학습용)
- 공장 조립 라인에서 부품(코드)을 투입하면 자동으로 조립(빌드), 불량 테스트(검증), 포장 및 운송(배포)까지 사람의 개입 없이 컨베이어 벨트로 이어 처리하는 생산 라인임

## Ⅱ. 특징

- 소스 저장소와의 연동을 통해 커밋($\text{Commit}$) 발생 시 자동으로 파이프라인이 기동하여 변경의 조기 검증이 가능함
- 모든 코드 배포 단계에 일관된 빌드 환경을 제공하여 개발자 로컬 PC와 운영 서버 간의 환경 차이로 인한 결함을 제거함
- 빌드 완료된 동일 아티팩트를 불변(Immutable) 상태로 보존하고 개발, 스테이징, 운영 단계로 점진적 승격하여 검증 안정성을 향상시킴
- 파이프라인 통과 조건에 테스트 코드 커버리지 및 취약점 스캔 지표를 의무화하여 보안적 품질 강제(Security Gate)를 구현할 수 있음

### 쉽게 이해하기 (학습용)
- 코드가 새로 추가될 때마다 알아서 전수조사를 하므로 버그 발견이 매우 빠르고, 모든 테스트 단계를 안전하게 거쳐야만 실제 서버에 배포되는 장치가 탑재됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 배포 흐름 | CI/CD 파이프라인 |
|:---|:---|:---|
| 프로세스 제어 방식 | 엔지니어가 수동으로 터미널 접속 및 배포용 실행 스크립트를 직접 구동함 | 소스 저장소의 WebHook 트리거 신호를 감지하여 빌드부터 배포까지 자동으로 단계가 체인화되어 실행됨 |
| 배포 무결성 검증 | 담당자가 직접 코드를 대조하거나 운영 환경 배포 완료 후 브라우저 접속 등으로 정상 동작 여부를 확인 검증함 | 단위 테스트 통과 및 정적 분석 커버리지 수치($\text{Coverage} \ge 80\%$) 불충족 시 빌드가 품질 게이트에서 자동 차단됨 |
| 장애 복구 및 롤백 | 시스템 장애 상황 시 수동으로 코드를 이전 버전으로 되돌리고 컴파일부터 배포 단계를 재수행해야 해 시간이 소요됨 | 사전 저장된 불변 아티팩트 버전을 활용해 롤백 명령 수행 즉시 직전 정상 서비스 버전 이미지로 자동 전환됨 |

> 요약: 배포 주기가 길고 환경 복잡성이 낮으면 수동 배포, 잦은 변경 통합과 무결성 보장을 위해서는 CI/CD 파이프라인이 유효함.

### 쉽게 이해하기 (학습용)
- 사람이 메일로 원고를 보낼 때마다 인쇄소 사장이 하나씩 확인하고 팩스로 책을 뽑는 방식과, 클라우드 저장소에 글을 등록하면 바로 판형 인쇄와 인쇄소 제본까지 한 번에 자동 처리되는 방식의 차이임

## Ⅳ. 구성요소 및 구조

```text
+--------------------------------------------------------------------------------+
|                             [ CI/CD Pipeline ]                                 |
|                                                                                |
|  +------------+      +------------+      +------------+      +------------+    |
|  |  변경 감지   | ---> |  자동 빌드   | ---> |  테스트/품질 | ---> |  자동 배포   |    |
|  |  (WebHook) |      | (Artifact) |      |   (Gate)   |      |  (Release) |    |
|  +------------+      +------------+      +------------+      +------------+    |
+--------------------------------------------------------------------------------+
                                                 │
                                                 ▼
                                        +-----------------+
                                        |  불변 레포지토리  |
                                        | (Docker/Maven)  |
                                        +-----------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 변경 감지 (Triggers) | 개발자 저장소 커밋 및 Pull Request 이벤트를 받아 파이프라인 에이전트를 가동시키는 WebHook 수신 장치임 |
| 빌드 도구 (Build Tools) | 소스 코드를 실행 파일 또는 컨테이너 이미지 등 패키지 형태로 컴파일하고 종속성을 결합하는 환경임 |
| 테스트 실행 및 품질 게이트 | 코드 무결성 검증을 위한 단위 테스트 수행 및 정적 코드 결함을 진단하는 검사 모듈임 |
| 아티팩트 레포지토리 | 배포용 컨테이너 이미지($\text{Docker Image}$ 등)나 패키지를 버전별로 안전하게 보관하는 안전 저장소임 |

> 요약: 트리거 감지로 빌드 및 패키징이 실행되면 품질 게이트를 거친 산출물이 안전 저장소에 등록되고 운영 환경으로 배포됨.

### 쉽게 이해하기 (학습용)
- 글이 감지되면 자동 타자기(빌드)가 인쇄를 뜨고 맞춤법 검사기(품질 게이트)를 거쳐 창고(레포지토리)에 완성 책자를 차곡차곡 쌓은 후 배달하는 시스템의 구성요소와 같음

## Ⅴ. 원리 및 절차 흐름도

```text
[1. Commit/WebHook 감지] -> [2. 아티팩트 빌드 수행] -> [3. 자동 테스트 실행] -> [4. 품질 게이트 검증] -> [5. 운영 자동 배포]
```

1. **Commit 및 WebHook 감지**: 개발자가 깃($\text{Git}$)에 코드를 반영하면 서버가 이벤트를 포착해 빌드 작업을 대기열에 적재함
2. **코드 컴파일 및 빌드**: 종속성 패키지를 로컬 캐시에서 불러오고 실행 가능한 불변 아티팩트를 컴파일 생성함
3. **단위 및 통합 테스트**: 사전에 구축된 자동 테스트 스크립트를 통해 신규 코드가 기존의 주요 비즈니스 기능을 훼손하는지 검사함
4. **정적 품질 검증**: 보안 취약성 정밀 스캔 및 단위 테스트 커버리지($\text{Coverage} \ge 80\%$) 적합 여부를 판정해 통과 조건을 평가함
5. **승격 및 배포 자동화**: 검증된 아티팩트를 목적 배포처에 배포 파이프라인 스크립트를 통해 이중화(Blue-Green 등) 배포함

> 요약: 커밋 감지 후 빌드, 테스트, 품질 검증 과정을 통과한 무결성 아티팩트 버전을 실제 운영 환경에 가동 중단 없이 자동으로 전파함.

### 쉽게 이해하기 (학습용)
- 책 기사가 접수(Commit)되면 기계가 판형을 찍고 오탈자를 기계로 걸러내어, 적합 점수 이상인 책자만 자동으로 트럭에 실어 전국 서점으로 배달하는 원리임

## Ⅵ. 실무 사례

- 실무에서는 모바일 커머스 시스템을 지속 운영하기 위해 Jenkins 또는 GitHub Actions 도구로 단위 테스트를 통과한 결과물에 한해 개발 환경 배포를 자동화함
- 대용량 트래픽 금융 웹서비스에서는 소나큐브(SonarQube) 정적 분석 결과 보안 결함이 발견되거나 코드 커버리지 $\ge 80\%$ 요건을 충족하지 못하면 품질 게이트 실패를 반환하고 운영 빌드를 즉시 중단함

### 쉽게 이해하기 (학습용)
- 모바일 쇼핑 앱 개발자들이 코드를 입력하면 밤사이 자동으로 검증되어 다음 날 아침 개발자 화면에 결함 통보 메일이 전송되도록 구축한 사례임

## Ⅶ. 결론

- CI/CD 파이프라인은 고빈도의 지속적인 제품 배포 환경에서 소스 품질 관리와 운영의 안정성을 제공하는 데보옵스($\text{DevOps}$) 환경의 핵심 인프라임
- 파이프라인의 설계 효율을 높이기 위해 불안정한 테스트(Flaky Test) 요소를 사전 제거하고, 빌드 병렬 처리 기법을 도입해 전체 수행 시간 임계치를 지속 단축해야 함

### 쉽게 이해하기 (학습용)
- 개발부터 배포까지의 수동 노동을 소프트웨어 기계 공정으로 전환하여, 빠른 출시 주기를 달성하면서도 오류의 유입을 원천 차단하는 가장 효과적인 방법임
