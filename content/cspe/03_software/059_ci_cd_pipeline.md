## 미리 알고가기

- CI는 작은 변경을 자주 통합해 빠르게 검증하는 개발 방식임
- CD는 검증된 변경을 배포 가능한 상태나 실제 운영 배포까지 자동화하는 흐름임
- 불변 아티팩트는 한 번 만든 산출물을 환경마다 다시 빌드하지 않고 그대로 승격하는 방식임

## Ⅰ. 개요

- **정의/개념**: CI/CD 파이프라인은 코드 변경이 저장소에 반영된 뒤 빌드와 테스트와 품질 검증과 배포 단계를 자동으로 거쳐 운영 반영까지 이어지도록 구성한 전달 자동화 체계임.
- **배경/필요성**: 배포 빈도가 높아질수록 수동 검증과 수작업 배포는 오류와 지연을 키우므로, 변경을 빠르고 반복 가능하게 전달하는 자동 경로가 필요함.

## Ⅱ. 특징

- 작은 변경을 자주 검증해 통합 리스크를 줄임
- 배포 절차의 재현성과 추적성을 높임
- 테스트 신뢰도와 환경 일관성이 낮으면 자동화가 불신을 키울 수 있음
- 품질과 보안 기준을 파이프라인 안에서 강제할 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 수동 배포 흐름 | CI/CD 파이프라인 |
|:---|:---|:---|
| 검증 방식 | 사람 중심으로 빌드와 테스트와 배포를 수행함 | 저장소 변경을 기준으로 자동 단계가 순서대로 실행됨 |
| 구조상 장점 | 초기 도입이 단순하고 소규모 운영에 맞기 쉬움 | 빠른 피드백과 반복 가능한 릴리스가 가능함 |
| 구조상 한계 | 오류와 지연이 누적되기 쉽고 추적성이 약함 | 구축과 유지에 자동화 설계 비용이 듦 |
| 적합한 환경 | 저빈도 배포나 작은 내부 시스템에 맞음 | 자주 배포하는 제품 조직과 플랫폼 조직에 맞음 |

> 요약: CI/CD의 핵심은 자동 배포 버튼이 아니라 작은 변경을 반복 가능한 절차로 믿고 전달하는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변경 감지 | 커밋과 병합을 감지해 파이프라인 실행을 시작함 |
| 빌드와 테스트 단계 | 컴파일과 단위 테스트와 정적 검사를 수행해 기본 결함을 걸러냄 |
| 품질 게이트 | 품질과 보안과 정책 기준을 통과한 변경만 다음 단계로 넘김 |
| 배포 단계 | 동일한 산출물을 환경별로 승격 배포해 재현성을 유지함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드 변경      | --> | 빌드/테스트    | --> | 품질 게이트    | --> | 배포/승격      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드 변경**: 커밋이나 병합이 자동 흐름을 시작함
2. **빌드 및 테스트**: 산출물을 만들고 핵심 검증을 수행함
3. **품질 게이트**: 실패 조건과 승인 기준을 확인함
4. **배포 및 승격**: 같은 산출물을 환경별로 배포함

## Ⅵ. 실무 적용 및 유의점

1. 웹 서비스 개발팀에서는 CI/CD가 배포 속도를 높이지만 테스트가 느리거나 자주 흔들리면 오히려 병목이 되므로 테스트 계층을 나누고 파이프라인 소요시간과 테스트 불안정 비율로 확인함
2. 여러 환경을 운영하는 조직에서는 자동화가 있어도 환경별 설정이 달라지면 재현성이 깨지므로 불변 아티팩트와 설정 표준을 함께 운영하고 환경 불일치 건수와 배포 롤백 비율로 확인함

## Ⅶ. 결론

CI/CD 파이프라인은 배포를 빠르게 하는 도구가 아니라 작은 변경을 신뢰 가능한 절차로 운영까지 전달하게 만드는 검증 체계임.
