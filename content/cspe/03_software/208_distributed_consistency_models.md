## 미리 알고가기

- 분산 일관성 모델은 여러 복제본의 연산 결과가 응용에 어떤 순서와 시점으로 관찰되는지 정의하는 계약임
- 선형화 가능성은 완료 시점의 실시간 선후를 지키는 단일 연산 순서를 제공함
- 순차 일관성은 모든 연산의 단일 순서와 프로세스별 프로그램 순서를 지키지만 실제 시간 순서는 요구하지 않음
- 인과 일관성은 프로그램 순서·읽기 후 쓰기·메시지 전달로 연결된 연산의 순서를 모든 노드에서 보존함
- 최종 일관성은 새 쓰기가 멈추면 복제본이 수렴한다는 조건이며 수렴 전 읽기 순서·최신성을 별도로 보장하지 않음
- ACID의 Consistency는 트랜잭션 전후 무결성 제약이고 분산 일관성은 연산 관찰 순서이므로 같은 용어를 혼동하면 안 됨

## 작성 근거(검토용)

- 일관성 모델은 관찰 순서, 실시간성, 인과성, 읽기 결과, 조정 범위, 분할 시 동작, 적합 조건으로 설명함
- 비교표는 선형화·순차·인과·최종 일관성이 보존하는 순서와 포기하는 보장을 같은 수준에서 대비함
- 재고 예약과 사용자 설정은 초과 예약·p99 커밋·자기 쓰기 읽기 위반·복제 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 분산 시스템 일관성 모델은 복제된 데이터의 읽기·쓰기 이력이 실시간·프로그램·인과 순서 중 무엇을 보존하고 어떤 이전 값을 허용하는지 규정하는 응용-저장소 계약임
- **배경/필요성**: 네트워크 지연·노드 장애·분할 상황에서 모든 복제본이 같은 시점에 갱신될 수 없으므로 업무 불변식과 허용 지연에 맞는 관찰 보장을 명시해야 함

## Ⅱ. 특징

- 모델 강도는 최신·과거 값이라는 표현만이 아니라 어떤 연산 순서를 모든 클라이언트가 공통으로 관찰하는지로 판정함
- 선형화 가능 읽기·쓰기는 리더·합의·Quorum과 읽기 장벽 등으로 완료 연산의 실시간 순서를 확인함
- 인과 일관성은 Version Vector·Logical Clock·Dependency Token으로 선행 연산이 반영된 복제본에서 읽게 함
- 최종 일관성은 비동기 복제와 충돌 병합으로 수렴하지만 자기 쓰기 읽기·단조 읽기는 Session Guarantee로 추가해야 함
- 네트워크 분할 중 조정할 수 없는 복제본은 강한 보장을 위해 요청을 거부하거나 약한 모델로 허용된 값을 반환해야 함
- 데이터 전체에 하나의 모델을 적용하지 않고 결제·재고·프로필·피드처럼 불변식과 허용 지연이 다른 연산별로 선택함

## Ⅲ. 종류 및 비교

| 판단 기준 | 선형화 가능성 | 순차 일관성 | 인과 일관성 | 최종 일관성 |
|:---|:---|:---|:---|:---|
| 공통 관찰 순서 | 실시간 선후를 지키는 단일 순서 | 프로그램 순서를 지키는 단일 순서 | 인과 관계가 있는 연산의 부분 순서 | 단일·인과 순서를 요구하지 않음 |
| 완료 쓰기 후 읽기 | 나중에 시작한 읽기가 해당 쓰기 이후 상태 관찰 | 다른 프로세스의 실제 시간과 다른 단일 순서에서 이전 상태 가능 | 인과 Token을 가진 읽기는 선행 쓰기 관찰 | 복제 지연 동안 이전 상태 가능 |
| 동시 쓰기 | 단일 연산 순서로 직렬화 | 합의된 단일 순서로 배치 | 인과 관계가 없으면 서로 다른 순서 허용 | 동시 버전을 사후 병합 가능 |
| 조정·메타데이터 | 리더·합의·Quorum·읽기 장벽 | 전역 순서화와 프로세스 순서 추적 | Dependency·Logical Clock·Session Token | 비동기 복제·Version·병합 규칙 |
| 분할 시 동작 | 순서 확인 불가 복제본은 요청 지연·거부 | 단일 순서 유지가 불가하면 처리 범위 제한 | 의존 버전을 보유한 복제본에서 처리 | 복제본별 처리를 허용할 수 있으나 충돌 병합 필요 |
| 적합 조건 | 중복 예약·Lock·리더 선출 | 실제 시간보다 단일 실행 순서가 중요 | 댓글·대화·사용자 세션의 원인-결과 | 카탈로그·피드·캐시의 지연 허용 복제 |

> 요약: 선형화는 실시간 단일 순서, 순차는 프로그램 순서의 단일 실행, 인과는 원인-결과 순서, 최종은 쓰기 중단 후 수렴을 보장함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Operation History | 호출·응답·읽은 값·쓴 값과 프로세스별 순서를 기록함 |
| Order·Version Metadata | Log Index·Term·Logical Clock·Version Vector로 연산 관계를 표현함 |
| Replication·Commit Policy | 리더·Quorum·비동기 전파 중 쓰기 완료 조건을 정함 |
| Read Policy·Session Token | 리더 읽기·Quorum 읽기·Bounded Staleness·자기 쓰기 읽기를 선택함 |
| Conflict Resolver | LWW·업무 병합·CRDT로 동시 버전의 최종 상태를 결정함 |
| Consistency SLI | 복제 지연·이전 값 비율·Session 위반·불변식 위반을 측정함 |

```text
Client Write -> Commit Order·Version -> Replicas
Client Read  -> Read Policy·Session Token -> Visible Version
```

> 요약: 쓰기 완료 정책과 순서 메타데이터가 복제 상태를 만들고 읽기 정책·Session Token이 노출 가능한 버전을 결정함.

## Ⅵ. 실무 사례

1. 재고 예약은 선형화 가능한 조건부 쓰기를 적용하고 초과 예약 건수·p99 커밋 지연을 확인함
2. 사용자 설정은 인과 관계 토큰과 자기 쓰기 읽기를 적용하고 자기 쓰기 읽기 위반률·복제 지연을 확인함

## Ⅶ. 결론

- 분산 일관성 모델은 업무 불변식·관찰 순서·허용 복제 지연·분할 중 처리 범위를 연산별로 선택해야 함
