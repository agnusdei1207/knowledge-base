## 미리 알고가기

- 일관성은 어느 노드에서 읽어도 같은 최신 값을 보게 하는 성질임
- 가용성은 요청을 받았을 때 실패보다 응답을 우선하는 성질임
- 분할 허용성은 네트워크가 끊겨도 시스템이 부분적으로 계속 동작해야 한다는 뜻임
- CP는 일관성을 더 우선하는 구성이고 AP는 가용성을 더 우선하는 구성임

## Ⅰ. 개요

- **정의/개념**: CAP 정리는 분산 시스템에서 네트워크 분할이 생겼을 때 일관성과 가용성을 동시에 끝까지 지키기 어렵고, 결국 무엇을 더 우선할지 정해야 한다는 원리임
- **배경/필요성**: 분산 저장소는 네트워크 단절을 피할 수 없으므로 장애 순간에 어떤 요청을 막고 어떤 요청을 계속 받을지 미리 정해 두어야 함

## Ⅱ. 특징

- CAP는 평상시보다 분할 장애가 났을 때의 선택을 설명함
- 분산 시스템에서는 분할 허용성을 버리기 어렵기 때문에 실제 판단은 주로 CP와 AP 사이에서 이뤄짐
- 일관성을 우선하면 일부 요청을 늦추거나 거절할 수 있음
- 가용성을 우선하면 잠시 오래된 값을 보여줄 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | CP | AP |
|:---|:---|:---|
| 분할 시 우선 가치 | 같은 최신 상태를 지킴 | 응답 지속을 지킴 |
| 쓰기 처리 | 충돌 가능성이 있으면 막거나 지연함 | 일단 받고 나중에 맞춤 |
| 분할 중 결과 | 불일치 가능 요청을 거부·지연 | 연결 가능한 노드가 요청을 처리하고 불일치 허용 |
| 대표 업무 | 분할 중 오래된 쓰기를 허용하지 않는 주문·재고 | 분할 중 응답을 유지하고 후속 병합하는 피드·추천 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 복제 노드 | 같은 데이터를 여러 위치에 나눠 가짐 |
| 분할 감지 | 노드 간 연결이 끊겼는지 판단함 |
| 일관성 정책 | 최신 상태를 어디까지 강하게 맞출지 정함 |
| 가용성 정책 | 분할 중에도 어떤 요청을 계속 받을지 정함 |

```text
+---------+      +---------+      +---------+
| 사용자 요청 | ---> | 복제본 1 | <--> | 복제본 2 |
+---------+      +---------+      +---------+
                           X
                    네트워크 분할 발생
                           X
                 CP는 차단, AP는 계속 처리
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 정상 복제 운영   | --> | 분할 장애 감지  | --> | CP/AP 정책 적용 | --> | 복구 뒤 상태 정합 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **정상 복제 운영**: 여러 노드가 데이터를 함께 유지함
2. **분할 장애 감지**: 노드 간 통신이 끊겼는지 확인함
3. **정책 적용**: 일관성을 지킬지, 응답을 계속 받을지 정함
4. **복구 뒤 정합**: 연결이 돌아오면 상태를 다시 맞춤

## Ⅵ. 실무 적용 및 유의점

1. 주문과 재고처럼 틀린 최신 상태가 바로 업무 오류로 이어지는 영역은 CP 성향으로 두고 분할 때 차단된 요청 비율과 복구 뒤 불일치 건수로 정책이 맞는지 확인함
2. 피드와 캐시처럼 잠시 늦은 값이 허용되는 영역은 AP 성향으로 두되 오래된 값이 얼마나 오래 보이는지 미리 정하고 데이터 지연 시간과 사용자 불만 건수로 허용 범위를 점검함

## Ⅶ. 결론

CAP의 핵심은 세 글자를 외우는 데 있지 않고 분할 장애가 났을 때 무엇을 지키고 무엇을 양보할지 업무별로 분명히 정하는 데 있음.
