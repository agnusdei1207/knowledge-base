## 미리 알고가기

- CAP는 분산 시스템에서 일관성과 가용성과 분할 허용성의 관계를 설명하는 정리임
- 네트워크 분할이 발생했을 때 어떤 속성을 우선할지 선택해야 함
- CAP는 평상시 전체 품질을 단순 3택으로 나누는 슬로건이 아님

## Ⅰ. 개요

- **정의/개념**: CAP 정리는 네트워크 분할이 발생한 분산 데이터 시스템에서 모든 노드가 같은 최신 데이터를 즉시 보장하는 일관성과 모든 요청에 응답하는 가용성을 동시에 완전하게 만족시키기 어렵고, 실제 설계에서는 분할 상황에서 무엇을 우선할지 선택해야 한다는 원리임
- **배경/필요성**: 분산 저장 시스템은 장애와 네트워크 단절을 피할 수 없으므로, 서비스가 분할 시 어떤 동작을 해야 하는지 미리 설계 기준을 가져야 함

## Ⅱ. 특징

- CAP는 분할 상황에서의 trade-off를 설명함
- CA 시스템도 네트워크 분할이 현실적으로 없다는 가정이 약함
- CP는 정합성을 지키기 위해 일부 요청을 지연 또는 거부할 수 있음
- AP는 응답성을 지키되 일시적 불일치를 허용함

## Ⅲ. 종류 및 비교

| 판단 기준 | CP | AP |
|:---|:---|:---|
| 분할 시 우선 가치 | 일관성 | 가용성 |
| 장점 | 최신 상태 신뢰성 높음 | 서비스 응답 지속 |
| 한계 | 지연과 일부 실패 허용 | 일시적 불일치 허용 |
| 적합 업무 | 금융·재고 핵심 데이터 | 소셜·캐시·추천 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Consistency Rule | 노드 간 동일 상태를 언제 보장할지 정의함 |
| Availability Rule | 요청 실패보다 응답 지속을 얼마나 우선할지 결정함 |
| Partition Detection | 네트워크 단절을 인지해 분할 모드로 전환함 |
| Fallback Behavior | 분할 시 읽기와 쓰기와 재동기화 정책을 구체화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 정상 복제 운영   | --> | 네트워크 분할 감지 | --> | CP/AP 정책 적용 | --> | 재동기화 수행   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **정상 복제 운영**: 노드 간 데이터를 동기화함
2. **네트워크 분할 감지**: 연결 끊김을 확인함
3. **CP 또는 AP 정책 적용**: 정합성 우선 또는 응답성 우선 동작을 수행함
4. **재동기화 수행**: 분할 해소 후 상태를 맞춤

## Ⅵ. 문제점 및 해결 방안

1. 문제: CAP를 단순 구호처럼 이해하면 서비스별 정합성 요구를 구분하지 못해 잘못된 분산 구조를 선택할 수 있음
   - 해결방안: operation별 consistency class를 정의하고 policy clarity score와 misrouted workload count로 검증함
2. 문제: 분할 시 동작을 미리 설계하지 않으면 장애 순간에 서비스가 예측 불가능한 응답과 데이터 충돌을 일으킬 수 있음
   - 해결방안: partition scenario drill을 운영하고 partition failover success rate와 unexpected behavior count로 검증함
3. 문제: AP 구조에서 불일치 허용 범위를 명시하지 않으면 사용자와 운영자가 데이터 신뢰도를 잘못 해석할 수 있음
   - 해결방안: staleness SLO를 정의하고 stale window compliance와 user-visible inconsistency rate로 검증함

## Ⅶ. 적용 사례

- 금융성 분산 저장소에서는 일관성 등급을 정의하고 확인 지표는 policy clarity score와 misrouted workload count임
- 멀티리전 서비스에서는 분할 시나리오 훈련을 운영하고 확인 지표는 partition failover success rate와 unexpected behavior count임
- 소셜 피드 시스템에서는 stale window를 명시하고 확인 지표는 stale window compliance와 user-visible inconsistency rate임

## Ⅷ. 결론

CAP의 실무 의미는 세 글자 암기가 아니라 분할 장애 시 서비스가 어떤 오류와 지연과 불일치를 감수할지 명확히 결정하는 데 있음.
