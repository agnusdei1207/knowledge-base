## Ⅰ. 개요
- **정의**: 생산자와 소비자 사이에 비동기 메시지 버퍼를 두어 결합도를 낮추는 미들웨어
- **배경/필요성**: 동기 호출 기반 서비스 간 통신에서 장애 전파·처리량 불균형 해소 필요
- **비유**: 우체통에 편지를 넣으면 수신자가 자기 속도로 꺼내 읽는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 비동기 통신 아키텍처 이해 | 큐 vs 토픽 구분, At-Least-Once 전달 보장 | 메시지 순서 보장 범위(파티션 단위 등) 명시 |

> 요약: 생산자·소비자 간 비동기 버퍼로 결합도를 낮추고 부하를 평활화하는 미들웨어임

## Ⅱ. 구성요소
```text
Producer --msg--> [ Queue / Topic ] --msg--> Consumer
                       |
                  +----+----+
                  |         |
              Broker     Storage
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Producer | 메시지를 생성하여 큐에 발행하는 주체 | 편지 발송인 |
| Broker | 메시지 라우팅·저장·전달을 수행하는 중간 서버 | 우체국 |
| Consumer | 큐에서 메시지를 수신하여 처리하는 주체 | 편지 수신인 |

> 요약: Producer가 Broker에 메시지를 발행하고 Consumer가 비동기로 수신·처리함

## Ⅲ. 절차
```text
메시지 발행 --> 브로커 저장 --> 소비자 전달 --> ACK 처리
```
- 1단계: Producer가 메시지를 직렬화하여 Broker의 큐/토픽에 발행
- 2단계: Broker가 메시지를 디스크/메모리에 저장하고 전달 보장 정책 적용
- 3단계: Consumer가 Pull 또는 Push 방식으로 메시지 수신·비즈니스 로직 처리
- 4단계: 처리 완료 후 ACK 전송, Broker가 해당 메시지를 소비 완료로 표시

> 요약: 발행, 저장, 전달, ACK 4단계로 메시지의 신뢰성 있는 비동기 전달 수행함

## Ⅳ. 문제점
- 메시지 유실: Broker 장애 시 미복제 메시지 손실 — 데이터 정합성 훼손
- 중복 소비: At-Least-Once 전달에서 재전송 발생 — 비멱등 처리 시 부작용
- 순서 역전: 다중 파티션·소비자 경쟁 시 발행 순서와 처리 순서 불일치

> 요약: 메시지 유실, 중복 소비, 순서 역전이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 복제 팩터 설정·동기 복제로 Broker 장애 시 메시지 유실 방지
2. 중기: 소비자 측 멱등성 키 기반 중복 처리 제거 로직 적용
3. 장기: 파티션 키 설계·단일 파티션 소비자 할당으로 순서 보장 범위 확보

> 요약: 동기 복제, 멱등성 처리, 파티션 키 설계로 단계적 개선함

## Ⅵ. 전망
- 발전 방향: 이벤트 스트리밍 플랫폼(Kafka 등)과의 경계 수렴으로 EDA(207 참조) 기반 확대
- 기술사적 판단: CQRS·Saga 패턴의 기반 인프라로 분산 트랜잭션 대체 수단 역할 확대
- 기술사 제언: 메시지 전달 보장 수준(At-Most/At-Least/Exactly-Once)별 트레이드오프 분석 필수
