## 미리 알고가기

- 객체 스토리지는 파일을 버킷·키 단위 객체로 저장하고 연산 자원과 독립 확장함
- 스키마 온 리드는 데이터를 읽는 시점에 구조와 타입을 해석하는 방식임
- Landing Zone은 원천 데이터를 변경하지 않고 처음 수용하는 저장 영역임
- Curated Zone은 품질·형식·메타데이터를 정리해 재사용 가능한 데이터를 제공하는 영역임
- 데이터 카탈로그는 데이터 위치·스키마·소유자·분류·계보 메타데이터를 검색 가능하게 관리함
- 작은 파일 문제는 파일 수 증가로 목록 조회·메타데이터·Task 생성 비용이 커지는 현상임

## 작성 근거(검토용)

- 데이터 레이크는 원천 형식 보존·객체 저장·스키마 온 리드·저장·연산 분리를 핵심으로 설명함
- 비교표는 데이터 웨어하우스와 데이터 형태·스키마·저장·처리·거버넌스·적합 업무를 대비함
- 절차는 원천 수용부터 메타데이터 등록·정제·소비까지 데이터 상태 변화가 있는 흐름만 사용함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 저장 구조와 운영 위험을 연결함

## Ⅰ. 개요

- **정의/개념**: 데이터 레이크는 여러 형식의 원천 데이터를 객체 스토리지에 저장하고 읽을 때 스키마를 적용하는 데이터 구조임
- **배경/필요성**: 사전에 용도를 정하기 어려운 로그·파일·이벤트를 보존하고 여러 처리 엔진이 재사용하기 위해 저장과 연산이 분리된 수용 계층이 필요함

## Ⅱ. 특징

- 원천 데이터를 변형 없이 보존해 새 분석 규칙의 재처리 기준으로 사용함
- 객체 스토리지와 열 파일 형식으로 저장 용량과 연산 자원을 독립 확장함
- 읽는 엔진이 스키마를 적용하므로 다양한 데이터 형태를 원천 그대로 수용함
- Landing·Raw·Curated 영역으로 원천 보존과 품질이 확인된 데이터의 경계를 나눔
- 카탈로그로 자산을 검색하고 파일 크기·수명주기로 스캔 비용을 통제함

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 웨어하우스 | 데이터 레이크 |
|:---|:---|:---|
| 데이터 형태 | 정제된 구조화 데이터 중심 | 구조화·반구조화·비구조화 데이터 |
| 스키마 적용 | 적재 전에 목표 스키마 확정 | 읽을 때 용도별 스키마 적용 |
| 저장 구조 | 관리형 테이블·열 저장 엔진 | 객체 스토리지의 파일·객체 |
| 처리 방식 | SQL 집계와 BI 질의 중심 | SQL·배치·ML·파일 처리 엔진 연계 |
| 거버넌스 기준 | 적재 단계의 모델·품질 통제 | 카탈로그·영역·수명주기 통제 필요 |
| 적합 업무 | 공통 지표와 반복 보고 | 원천 보존·탐색 분석·모델 학습 |

> 요약: 데이터 레이크는 다양한 원천을 객체 스토리지에 보존하고 카탈로그와 영역 관리로 재사용 범위를 통제함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Ingestion | 파일·로그·이벤트·DB 변경분을 배치 또는 스트림으로 수집함 |
| Object Storage | 원천과 가공 데이터를 객체로 저장하고 연산과 독립 확장함 |
| Data Zone | Landing·Raw·Curated 경계로 원천 변경 여부와 품질 수준을 구분함 |
| Catalog·Metadata | 위치·스키마·분류·소유자·계보를 등록해 검색과 접근 판단을 지원함 |
| Processing Engine | 분산 SQL·배치·스트림·ML 엔진이 목적별 스키마로 데이터를 읽음 |
| Governance·Lifecycle | 접근 정책·암호화·보존 기간·삭제와 파일 크기를 관리함 |

```text
DB·로그·파일 -> Landing·Raw -> Curated -> SQL·ML·응용
                      |            |
                  Catalog ---- Governance
```

> 요약: 객체 스토리지의 영역별 데이터와 카탈로그·거버넌스가 처리 엔진의 검색·접근·재처리를 지원함.

## Ⅴ. 원리 및 절차 흐름도

```text
원천 수용 -> 메타데이터 등록 -> 형식·품질 정제 -> Curated 게시 -> 목적별 소비
```

1. **원천 수용**: 데이터와 수집 시각·원천 위치를 Landing 영역에 변경 없이 저장함
2. **메타데이터 등록**: 카탈로그에 스키마·분류·소유자·파티션 정보를 기록함
3. **정제 처리**: 중복·누락·형식을 검사하고 분석 가능한 파일 크기와 형식으로 변환함
4. **데이터 게시**: 품질 규칙을 통과한 데이터를 Curated 영역과 카탈로그에 공개함
5. **목적별 소비**: SQL·ML·응용 엔진이 필요한 스키마와 파티션을 선택해 읽음

> 요약: 데이터 레이크는 원천을 보존한 뒤 메타데이터와 품질 기준을 적용해 재사용 가능한 데이터로 게시함.

## Ⅵ. 실무 사례

1. 응용 로그 레이크는 서비스·날짜로 파티셔닝하고 평균 파일 크기·질의 스캔량을 확인함
2. 모델 학습 데이터는 원천 버전과 계보를 등록하고 미등록 데이터셋 수·입력 버전 일치율을 확인함

## Ⅶ. 결론

- 데이터 레이크는 원천 보존·파일 구조·카탈로그 범위·품질 구역과 스캔 비용을 기준으로 운영해야 함
