## 미리 알고가기

- 무결성 제약조건은 데이터베이스가 허용할 수 있는 값과 관계를 미리 정해 두는 규칙임
- 도메인 무결성은 값의 범위를, 개체 무결성은 기본키를, 참조 무결성은 외래키 관계를 다룸
- 같은 규칙을 여러 프로그램이 함께 써도 흔들리지 않게 하려면 저장소 수준에서 강제해야 함

## Ⅰ. 개요

- **정의/개념**: 데이터베이스 무결성 제약 조건은 값의 범위와 기본키의 유일성과 테이블 간 참조 관계 같은 데이터 규칙을 데이터베이스 자체에 명시해 잘못된 상태 저장을 사전에 막는 통제 장치임.
- **배경/필요성**: 같은 데이터를 웹 화면과 배치와 외부 연동이 함께 바꾸는 환경에서는 애플리케이션마다 규칙을 따로 두면 누락이 생기므로, 저장소 수준에서 공통 규칙을 강제해야 함.

## Ⅱ. 특징

- 데이터를 저장하는 순간 오류 상태를 막아 사후 정리 비용을 줄임
- 여러 애플리케이션이 같은 데이터베이스를 써도 같은 규칙을 적용할 수 있음
- 제약조건이 약하면 중복과 고아 데이터와 잘못된 값이 쌓이기 쉬움
- 제약조건을 설계 없이 늘리면 대량 적재와 스키마 변경이 어려워질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 도메인 무결성 | 개체 무결성 | 참조 무결성 |
|:---|:---|:---|:---|
| 통제 대상 | 값의 범위와 형식과 기본값 | 기본키의 유일성과 NULL 금지 | 부모와 자식 테이블의 연결 관계 |
| 대표 수단 | CHECK와 데이터 타입과 DEFAULT | PRIMARY KEY와 UNIQUE | FOREIGN KEY와 삭제 정책 |
| 막는 문제 | 형식 오류와 비정상 값 저장 | 중복 행과 식별 불가 상태 | 고아 데이터와 잘못된 참조 |
| 주 적용 시점 | 컬럼 설계 단계 | 테이블 식별자 설계 단계 | 테이블 관계 설계 단계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 값 제약 규칙 | 컬럼별 허용 범위와 형식과 기본값을 정해 잘못된 값을 막음 |
| 키 제약 규칙 | 기본키와 후보키로 각 행이 유일하게 식별되도록 함 |
| 관계 제약 규칙 | 외래키로 부모와 자식의 연결이 깨지지 않게 함 |
| 적용 정책 | 저장과 삭제와 마이그레이션 시 어떤 순서로 검증할지 정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 규칙 정의      | --> | 스키마 반영     | --> | 저장 시 검증    | --> | 예외/보정 처리  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **규칙 정의**: 업무 규칙을 값과 키와 관계 기준으로 정리함
2. **스키마 반영**: 제약조건을 테이블 정의에 반영함
3. **저장 시 검증**: 입력과 수정 시 위반 여부를 검사함
4. **예외와 보정 처리**: 위반 데이터는 막거나 별도 보정 절차로 넘김

## Ⅵ. 실무 적용 및 유의점

1. 여러 채널이 같은 DB를 갱신하는 환경에서는 핵심 업무 규칙을 애플리케이션에만 두지 말고 DB 제약으로 끌어올려야 하며 무결성 위반 건수와 채널 간 데이터 불일치율로 확인함.
2. 대량 이관과 배치 적재에서는 제약조건을 한꺼번에 강하게 걸면 실패 범위가 커지므로 단계적으로 적용하고 이관 실패율과 정합성 보정 완료율로 확인함.

## Ⅶ. 결론

무결성 제약조건은 잘못된 데이터를 나중에 정리하는 대신 저장 단계에서 바로 차단하도록 만드는 가장 기본적인 데이터 통제 장치임.
