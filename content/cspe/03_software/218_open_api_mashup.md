## Ⅰ. 개요
- 기업의 자산(데이터, 기능)을 외부 개발자에게 공개하여 새로운 가치를 창출하는 기술임
- 매쉬업은 서로 다른 Open API를 결합하여 혁신적인 융합 서비스를 만드는 행위임
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | REST/JSON, OAuth2 보안, API 생태계, 창조적 파괴 | 레고 블록 공개 및 창의적 조립 |

## Ⅱ. 구성요소
- 인터페이스(API), 데이터 포맷(JSON), 보안(OAuth), 제공 플랫폼으로 구성됨
[지도 API] + [공공 데이터] --(Mashup)--> [맛집 찾기 앱]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| REST API | HTTP 메소드(GET/POST 등)를 활용한 자원 기반 인터페이스 | 표준화된 주문 메뉴판 |
| JSON | 경량의 텍스트 기반 데이터 교환 형식 (Key-Value) | 간결한 영수증 |
| OAuth 2.0 | 사용자의 비밀번호 노출 없이 접근 권한을 위임하는 보안 표준 | 임시 출입증 카드 |
> 요약: 개방성, 경량성, 접근 용이성을 바탕으로 플랫폼 비즈니스의 핵심이 됨

## Ⅲ. 절차
- API 제공 및 매쉬업 서비스 구축 절차임
[API 설계/공개] -> [개발자 포털 등록] -> [매쉬업 기획] -> [융합 서비스 배포]
- 4단계 설명
1) API 디자인: Swagger(OpenAPI Spec) 등을 사용하여 표준화된 인터페이스 정의함
2) 보안 설정: API Key 발급 및 Rate Limiting(호출 제한)을 통해 자원 보호함
3) 데이터 결합: 서로 다른 도메인의 API를 호출하여 데이터를 정제 및 통합함
4) 프레젠테이션: 결합된 데이터를 사용자 친화적인 UI(지도, 차트 등)로 시각화함
> 요약: 외부 자원을 창의적으로 조합하여 개발 비용을 낮추고 타임투마켓을 단축함

## Ⅳ. 문제점
- 외부 API 중단 시 해당 매쉬업 서비스도 마비되는 의존성 리스크 존재함 (원인: 공급망 종속)
- 무분별한 데이터 결합으로 인한 개인정보 유출 및 보안 위협 증대함 (원인: 데이터 오남용)

## Ⅴ. 개선방안
- (단기) API 상태 모니터링 및 장애 대비용 캐싱/대체 수단(Fallback) 마련함
- (중기) API Gateway를 통한 통합 인증, 모니터링 및 과금 체계 구축함
- (장기) API 거버넌스 수립을 통해 데이터 주권 보호 및 라이선스 준수 강화함

## Ⅵ. 전망
- 금융권의 '마이데이터' 사업처럼 전 산업 분야의 데이터 개방이 가속화될 것임
- AI 모델 자체를 API로 제공하는 'AI-as-a-Service'와 매쉬업되는 지능형 앱이 주류가 될 것임
