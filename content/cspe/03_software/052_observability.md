## Ⅰ. 개요
- 정의: 시스템 외부 출력을 통해 내부 상태를 명확히 이해하고 장애 원인을 추론할 수 있는 능력.
- 출제 의도: 단순 모니터링을 넘어 복잡한 분산 시스템의 가시성 확보를 위한 3대 요소 이해도 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Logging ] (What happened? - Event details)
     |
  [ Metrics ] (Is it OK? - Aggregate numbers)
     |
  [ Tracing ] (Where is the bottleneck? - Request flow)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 로깅 (Logging) | 타임스탬프와 함께 기록된 개별 이벤트의 상세 이력 | 일기장 |
| 메트릭 (Metrics) | 시간에 따른 수치 데이터 집합 (CPU 사용률 등) | 건강 수치/계기판 |
| 트레이싱 (Tracing) | 분산 환경에서 요청의 시작부터 끝까지 전 경로 추적 | 택배 배송 추적 |
> 요약: 세 요소를 통합하여 장애의 증상(Metric), 원인(Log), 위치(Trace)를 파악함.

## Ⅲ. 절차
- ASCII 흐름도
  [데이터 생성] -> [수집 및 전송] -> [저장/인덱싱] -> [시각화/상관 분석]
- 4단계 설명
1. 애플리케이션 코드에 계측(Instrumentation) 도구를 심어 데이터를 생성함.
2. 수집 에이전트(OTEL Collector 등)가 데이터를 표준 포맷으로 변환 및 통합함.
3. 중앙 저장소에 데이터를 적재하고 빠른 검색을 위해 인덱싱함.
4. 통합 대시보드(Grafana 등)에서 데이터 간 연관성을 분석하여 통찰 도출함.
> 요약: 산재된 파편 데이터를 연결하여 시스템 전체의 맥락(Context)을 파악함.

## Ⅳ. 문제점
- 데이터 과적: 로그 및 트레이스 양이 급증하여 저장 비용 상승 및 시스템 성능 저하 유발함.
- 사일로 도구: 각각 다른 벤더 도구 사용 시 데이터 연동이 안 되어 종합 분석 어려움.

## Ⅴ. 개선방안
- OpenTelemetry (OTel): 데이터 수집 표준을 통합하여 도구 간 호환성 및 벤더 독립성 확보함.
- 샘플링 전략: 트레이스 데이터 전체 대신 일부만 유의미하게 추출하여 비용 효율화함.

## Ⅵ. 전망
- 'MELT' (Metrics, Events, Logging, Tracing) 데이터의 통합 분석 플랫폼 시장 경쟁 가속화됨.
- AI 엔진이 방대한 데이터를 분석하여 이상 징후를 선제적으로 알려주는 AIOps 적용 확대됨.
- 'eBPF' 기술을 통해 애플리케이션 수정 없이 인프라 수준에서 투명한 가시성 확보 기술 고도화됨.
