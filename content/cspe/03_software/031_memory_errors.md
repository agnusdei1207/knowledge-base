## Ⅰ. 개요
- 정의: 허용되지 않은 메모리 영역 접근(Segfault)과 할당된 메모리 미해제 현상(Leak)
- 배경: C/C++ 등 저수준 언어에서 개발자의 수동 메모리 관리 실수로 발생하며 시스템 불안정 초래
- 출제 의도: 메모리 보호 메커니즘의 위반 원인과 누적된 미해제 자원의 여파 분석 역량 평가

## Ⅱ. 구성요소
```
[ Segfault ] : Access to NULL / Read-only / Kern Space
[ Memory Leak ] : malloc() -> (No free) -> exit? No, stays in RAM
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 세그멘테이션 폴트 | MMU가 하드웨어적으로 감지하는 잘못된 주소 참조 | 무단 침입 |
| 메모리 릭 | 참조되지 않는 메모리가 해제되지 않고 점유 중인 상태 | 물이 새는 수조 |
| 코어 덤프 | Segfault 발생 시 상태를 파일로 기록하여 분석에 활용 | 블랙박스 기록 |
> 요약: 폴트는 즉각적 크래시를, 릭은 서서히 진행되는 성능 고갈을 의미함.

## Ⅲ. 절차
```
[Illegal Access] -> [MMU Exception] -> [Kernel Signal] -> [Terminated] (Segfault)
[Alloc] -> [Use] -> [Lose Reference] -> [Unreachable but Occupied] (Leak)
```
1. (폴트) 프로그램이 유효하지 않은 포인터나 읽기 전용 영역에 쓰기 시도
2. (폴트) 하드웨어 MMU가 예외를 발생시키고 커널이 SIGSEGV 시그널을 프로세스에 전달
3. (릭) 힙(Heap) 영역에 자원을 할당받은 후 해당 주소를 담은 변수값이 소멸됨
4. (릭) 해제할 방법이 없어진 메모리는 시스템 종료 전까지 반환되지 않고 누적됨
> 요약: 보호 규칙 위반에 따른 강제 종료 또는 자원 고갈의 과정을 거침.

## Ⅳ. 문제점
- 원인: 와일드 포인터(Wild Pointer)나 버퍼 오버플로우로 인한 메모리 오염 및 보안 위협
- 원인: 장시간 가동되는 서버 프로그램에서 릭 발생 시 가용한 물리 메모리 부족으로 시스템 마비

## Ⅴ. 개선방안
- (단기) Valgrind, AddressSanitizer 등 동적 분석 도구를 활용하여 런타임 오류 검출
- (중기) 스마트 포인터(unique_ptr, shared_ptr) 활용으로 메모리 생명주기 자동 관리
- (장기) 러스트(Rust)와 같이 컴파일 시점에 메모리 안전성을 검증하는 언어 도입 확대

## Ⅵ. 전망
- 하드웨어 태깅 기술(MTE)의 보급으로 런타임 메모리 오류를 더 정교하고 빠르게 감지할 것으로 기대
- AI 기반 코드 분석 기술이 개발 단계에서 잠재적 메모리 결함을 사전에 탐지하는 기술이 표준화될 것임
