## Ⅰ. 개요
- 정의: 기업 내 서로 다른 시스템(ERP, CRM 등) 간의 데이터를 연계 및 통합하는 솔루션임
- 배경: Point-to-Point 방식의 복잡도 증가(Spaghetti 현상) 해결 및 데이터 정합성 유지
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 토폴로지 | Hub-and-Spoke, Bus | 매우높음 |
| 통합 수준 | Data, App, Process | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ 시스템 A ]     [ 시스템 B ]
      |               |
  [ 어댑터 ] ----- [ 허브 ] ----- [ 어댑터 ]
                    |
               [ 시스템 C ]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 어댑터 (Adapter) | 각 시스템의 독자적 프로토콜을 변환 | 전원 플러그 돼지코 |
| 허브 (Hub) | 데이터 라우팅 및 중앙 집중식 통제 수행 | 중앙 환승역 |
| 브로커 (Broker) | 데이터 포맷 변환 및 규칙 기반 라우팅 | 동시 통역사 |

> 요약: 어댑터·허브·브로커로 시스템별 프로토콜, 데이터 형식, 전송 경로를 중앙 관리함

## Ⅲ. 절차
- ASCII 흐름도
  [연계 대상식별] -> [인터페이스 설계] -> [데이터 변환] -> [메시지 전송]
     (송수신 정의)      (매핑/룰 설정)      (Parsing)         (Routing)

- 4단계 설명
1. 분석설계: 연계할 소스/타겟 시스템을 정의하고 데이터 레이아웃을 확정함
2. 어댑터설치: 각 시스템의 API나 DB에 접속하기 위한 연결 모듈을 설정함
3. 룰정의: 데이터 변환 로직(Mapping)과 전송 순서(Workflow)를 정의함
4. 모니터링: 데이터 송수신 상태를 실시간 확인하고 오류 발생 시 재전송함

> 요약: 송수신 인터페이스를 정의하고 데이터 변환·라우팅·재전송 규칙으로 연계 흐름을 처리함

## Ⅳ. 문제점
- 허브 시스템 장애 시 전체 연계 서비스가 중단되는 단일 장애점(SPOF) 문제 있음
- 대용량 트래픽 발생 시 중앙 허브의 성능 병목 현상이 발생할 가능성 높음

## Ⅴ. 개선방안
- (단기) 허브 시스템의 이중화 및 장애 복구(Failover) 체계 강화함
- (중기) 서비스 중심 아키텍처(SOA) 또는 ESB(Enterprise Service Bus)로 확장함
- (장기) 클라우드 환경에 최적화된 iPaaS(Integration PaaS)로 전환하여 유연성 극대화함

## Ⅵ. 전망
- 마이크로서비스(MSA) 간 경량 메시지 큐(Kafka, RabbitMQ)를 활용한 연계 비중 확대됨
- API 거버넌스와 결합하여 내부 시스템뿐만 아니라 외부 생태계와의 통합 가속화됨
