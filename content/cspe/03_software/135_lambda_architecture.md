## 미리 알고가기

- 람다 아키텍처는 전체 원본을 재계산하는 배치 계층과 최근 이벤트를 증분 처리하는 속도 계층을 병행함
- 배치 계층(Batch Layer)은 불변 원본 데이터로 배치 뷰를 재생성함
- 속도 계층(Speed Layer)은 최신 배치 뷰에 아직 포함되지 않은 이벤트로 실시간 뷰를 갱신함
- 제공 계층(Serving Layer)은 배치 뷰를 색인하고 조회 시 실시간 뷰와 결합해 최신 결과를 제공함
- 배치·속도 계층에 같은 계산 규칙을 각각 구현하므로 코드 중복과 결과 불일치 관리가 필요함

## 작성 근거(검토용)

- 람다 아키텍처는 불변 원본·배치 뷰·실시간 뷰·결과 결합과 이중 처리 로직을 핵심 축으로 설명함
- 비교표는 Kappa와 처리 경로·과거 재계산·최신 반영·결과 제공·운영 부담·적합 조건을 대비함
- 실무 사례는 애플리케이션 이벤트와 추천 특성 집계를 결과 차이·반영 시간·재계산 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: 람다 아키텍처는 불변 원본의 배치 재계산과 최신 이벤트의 실시간 증분 처리를 병행하고 두 결과를 조회 시 결합하는 데이터 처리 구조임
- **배경/필요성**: 전체 원본으로 결과를 다시 만들 수 있는 복구 능력과 최신 이벤트를 낮은 지연으로 반영하는 요구를 한 처리 경로로 충족하기 어려워 두 계산 계층을 병행함

## Ⅱ. 특징

- 수집 이벤트를 불변 원본 데이터에 추가하면서 속도 계층에도 전달함
- 배치 계층이 전체 원본으로 배치 뷰를 주기적으로 재생성해 계산 규칙 변경과 오류 수정을 반영함
- 속도 계층이 최신 배치 뷰 이후의 이벤트만 증분 계산해 실시간 뷰를 갱신함
- 새 배치 뷰가 배포되면 해당 구간의 실시간 결과를 대체하고 조회 시 두 뷰를 결합함
- 동일 계산 규칙을 배치·속도 계층에 각각 구현하므로 배포 동기화와 결과 차이 관리가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Lambda Architecture | Kappa Architecture |
|:---|:---|:---|
| 처리 경로 | 배치 계층과 속도 계층을 병행 | 하나의 스트림 처리 경로를 사용 |
| 재처리 범위 | 불변 원본 전체를 재계산해 배치 뷰를 만들고 속도 계층이 최신만 증분 갱신 | 보존 이벤트를 동일 스트림에 재생해 과거·최신을 함께 처리 |
| 운영 부담 | 두 계산 로직과 결과 정합성 관리 | 재생 처리량과 스트림 상태 관리 |

> 요약: Lambda는 배치·속도 계층의 결과를 결합하고, Kappa는 보존 이벤트를 한 스트림 처리 경로로 재생함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 수집·불변 원본 | 이벤트를 배치 재계산이 가능한 추가 전용 데이터로 보존함 |
| 배치 계층 | 전체 원본을 주기적으로 계산해 배치 뷰를 생성함 |
| 속도 계층 | 배치 뷰에 포함되지 않은 최신 이벤트로 실시간 뷰를 갱신함 |
| 제공 계층·배치 뷰 | 배치 결과를 색인하고 새 버전으로 교체해 조회에 제공함 |
| 실시간 뷰·조회 계층 | 배치 뷰와 최신 증분 결과를 결합해 응답함 |

```text
              +-> 불변 원본 -> 배치 계층 -> 배치 뷰 --+
이벤트 수집 --+                                      +-> 결합 조회
              +-> 속도 계층 ----------> 실시간 뷰 --+
```

> 요약: 같은 이벤트가 불변 원본과 속도 계층으로 들어가며 조회 계층은 배치 뷰와 실시간 뷰를 결합함.

## Ⅴ. 원리 및 절차 흐름도

```text
이벤트 이중 전달 -> 실시간 뷰 갱신 -> 배치 뷰 재계산 -> 배치 뷰 교체 -> 두 뷰 결합
```

1. **이벤트 이중 전달**: 수집 이벤트를 불변 원본에 추가하고 속도 계층에도 전달함
2. **실시간 뷰 갱신**: 속도 계층이 최신 배치 이후의 이벤트를 계산함
3. **배치 뷰 재계산**: 배치 계층이 전체 원본과 현재 계산 규칙으로 결과를 다시 생성함
4. **배치 뷰 교체**: 제공 계층이 새 배치 뷰를 배포하고 포함 구간의 실시간 결과를 정리함
5. **두 뷰 결합**: 조회 계층이 배치 결과와 아직 포함되지 않은 실시간 결과를 합쳐 반환함

> 요약: 속도 계층의 임시 증분 결과는 전체 원본으로 재계산한 새 배치 뷰가 배포될 때 대체됨.

## Ⅵ. 실무 사례

1. 애플리케이션 이벤트 대시보드는 최근 집계를 속도 계층에 반영하고 계층 간 결과 차이·배치 반영 시간을 확인함
2. 추천 특성 집계는 불변 원본으로 배치 뷰를 재계산하고 재계산 시간·이중 로직 결함 건수를 확인함

## Ⅶ. 결론

- 람다 아키텍처는 전체 원본 재계산과 최신 이벤트 반영이 모두 필요하고 이중 처리 로직을 관리할 수 있을 때 적용해야 함
