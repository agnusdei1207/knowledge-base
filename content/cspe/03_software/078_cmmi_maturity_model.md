# 📖 【암기용】 개념 완전 이해

> 목적: CMMI를 처음 봐도 조직의 개발 프로세스가 개인 역량 의존에서 정량 관리와 지속 개선으로 성숙하는 모델로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: CMMI는 조직의 프로세스 능력과 성숙도를 단계별로 평가·개선하는 모델임
- **왜 필요한가**: 프로젝트 성패가 개인 경험에만 의존하면 일정·품질·비용 예측이 흔들림. CMMI는 반복 가능한 프로세스와 측정 기반 개선을 요구함.
- **핵심 직관**: 요리사가 바뀌어도 같은 품질의 음식을 내도록 레시피, 교육, 측정, 개선 루프를 갖추는 과정임.

## 깊이 이해
- **배경·문제의식**: 소프트웨어 조직은 요구 변경, 일정 지연, 품질 편차를 반복함. CMMI는 이런 편차를 프로세스 성숙도 관점에서 줄이기 위해 등장함.
- **작동 원리**: 성숙도는 1 Initial, 2 Managed, 3 Defined, 4 Quantitatively Managed, 5 Optimizing으로 구분함. 각 수준은 프로세스 영역, 제도화, 측정, 개선 활동을 요구함.
- **비유**: 개인 감으로 운전하던 물류회사가 표준 운행 경로, 배송 시간 측정, 지연 원인 분석, 자동 배차 개선으로 발전하는 과정과 같음.
- **구체 예시**: 요구사항 관리와 프로젝트 계획이 문서화되면 Level 2 기반이 되고, 조직 표준 프로세스와 교육 체계가 적용되면 Level 3로 평가 가능함.
- **흔한 오해·주의점**: CMMI는 문서량을 늘리는 제도가 아님. 실제 프로젝트 성과 지표와 프로세스 내재화가 appraisal의 핵심임.

## 연결 개념
- Process Area — CMMI에서 개선을 요구하는 프로세스 영역
- Appraisal — 조직 성숙도 평가 절차
- ISO/IEC 15504 SPICE — 프로세스 평가 모델 비교 대상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: CMMI는 인증 명칭보다 프로세스 영역을 조직에 제도화하고 정량 지표로 프로젝트 예측성과 개선 능력을 높이는 모델이다.

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: CMMI는 소프트웨어·시스템 개발 조직의 프로세스 성숙도를 1~5단계로 평가하고 개선하는 모델이다.
> 2. **가치**: 요구관리, 프로젝트계획, 품질보증, 측정분석, 정량관리, 원인분석을 통해 일정·품질·비용 편차를 줄임.
> 3. **판단 포인트**: 성숙도 레벨 달성보다 프로세스 제도화, 실제 프로젝트 적용률, 지표 기반 개선 루프가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CMMI 단계 이해 확인 | Level 1~5, process area, institutionalization | 단순 인증 레벨 암기로 작성 |
| 프로세스 개선 판단 확인 | 현황 진단, gap 분석, 개선 로드맵 | 문서 작성량 증가로 오해 |
| 평가·운영 역량 확인 | appraisal, metric, quantitative management | 프로젝트 적용률·성과 지표 누락 |

> 요약: 이 문제는 성숙도 단계 설명과 함께 조직 프로세스 개선 로드맵을 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 조직 프로세스 성숙도 모델
- 배경: 프로젝트 수행이 개인 역량에 의존하면 일정 지연, 산출물 품질 편차, 재작업이 반복되고 조직 차원의 재현 가능한 수행 기준이 남지 않는다.
- 필요성: CMMI는 성숙도 1~5단계와 프로세스 영역으로 표준화, 제도화, 정량 관리를 점검해 프로젝트 예측성과 개선 근거를 확보한다.

---

## Ⅱ. 구조 및 구성요소

```text
Organization Goal -> Process Area Selection
  -> Practice Implementation -> Institutionalization
  -> Appraisal -> Maturity Level -> Improvement Roadmap
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Maturity Level | 조직 성숙도 단계 | 1 Initial ~ 5 Optimizing |
| Process Area | 개선 대상 프로세스 묶음 | 요구관리, 품질보증, 측정분석 |
| Specific/Generic Practice | 영역별 실행·제도화 활동 | 수행 증거와 반복 적용 필요 |
| Appraisal | 성숙도 평가 | SCAMPI 계열, evidence 기반 |
| Improvement Roadmap | gap 해소 계획 | 6~12개월 단위 개선 과제 |

> 요약: CMMI 구조는 프로세스 영역 실행, 제도화, 평가, 성숙도 판정, 개선 로드맵으로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Current Process Assessment -> Gap Analysis
  -> Target Level Select -> Process Standardize
  -> Pilot Project -> Organization Rollout
  -> Appraisal -> Continuous Improvement
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 현행 프로세스와 산출물 진단 | 프로젝트 표본 3개 이상 |
| 2 | 목표 레벨과 프로세스 영역 gap 분석 | Level 2/3 우선순위 |
| 3 | 표준 프로세스·템플릿·교육 수립 | 조직 적용률 80% 이상 |
| 4 | 파일럿 프로젝트 적용과 지표 수집 | 일정편차, 결함밀도, 재작업률 |
| 5 | appraisal 수행과 개선 과제 갱신 | evidence 충족, action item 관리 |

> 요약: CMMI 개선은 현황 진단, gap 분석, 표준화, 파일럿, 평가, 지속 개선 순서로 수행된다.

---

## Ⅳ. 특징

| 구분 | 비관리 프로세스 | CMMI 적용 | 정량 기준 |
|:---|:---|:---|:---|
| 수행 방식 | 개인 경험 의존 | 조직 표준 프로세스 | 적용률 80% 이상 |
| 관리 수준 | 일정·품질 사후 대응 | 계획·측정·예측 관리 | 일정편차 10% 이하 |
| 품질 활동 | 프로젝트별 편차 | PPQA, verification | 결함밀도 추세 |
| 개선 | 문제 발생 후 조치 | causal analysis, optimization | 재발률 감소 |
| 평가 | 자체 판단 | appraisal evidence | 레벨 1~5 |

> 요약: CMMI는 프로세스 수행을 조직 표준과 측정 지표로 제도화해 프로젝트 편차를 줄이는 모델이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | ISO 9001은 품질경영 일반 | CMMI는 개발 프로세스 성숙도 | 개발 조직 개선 목적이면 CMMI |
| 비용/성능 | 자체 프로세스 개선 | 모델 기반 단계 개선 | 대형 SI·공공 수주 요구 시 |
| 운영/위험 | 문서 중심 운영 위험 | 제도화·지표 중심 적용 | 적용률과 성과 지표로 통제 |
| 개선 | 일회성 감사 | 지속적 개선 로드맵 | 6~12개월 단위 계획 |

> 요약: CMMI는 조직 개발 프로세스를 단계적으로 성숙시키고 평가 증거가 필요한 환경에 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문서 형식화 | appraisal 통과 목적 | 프로젝트 적용률과 성과 지표 연결 | 표준 프로세스 적용률 |
| 현장 저항 | 절차 증가 체감 | lightweight template, 교육 | 교육 이수율, 사용률 |
| 비용 증가 | 범위 과다 | 목표 레벨·영역 단계 적용 | 개선 과제 완료율 |
| 지표 왜곡 | 숫자 맞추기 | 자동 수집, 품질 리뷰 | 결함 재오픈율 |

> 요약: CMMI 적용 리스크는 현장 적용률, 경량화, 단계 범위, 지표 신뢰성으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 프로세스 적용 | 표준 프로세스 적용률 80% 이상 | 프로젝트 산출물 감사 |
| 일정 예측 | 일정편차 10% 이하 | 계획 대비 실적 |
| 품질 | 결함밀도 20% 감소, 재오픈율 5% 이하 | 결함관리 시스템 |
| 개선 | action item 완료율 90% 이상 | 개선 로드맵 추적 |

> 요약: CMMI 성과는 레벨보다 프로세스 적용률, 일정편차, 결함밀도, 개선 과제 완료율로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 요구관리, 프로젝트계획, 형상관리, PPQA, 측정분석 영역을 Level 2 기반 과제로 선정하고 6개월 개선 로드맵을 수립함.
2. 조직 표준 프로세스와 산출물 템플릿을 수립하되 프로젝트 규모별 lightweight tailoring 기준을 두어 현장 적용률 80% 이상을 목표로 함.
3. appraisal 전 파일럿 2~3개 프로젝트에서 일정편차, 결함밀도, 재작업률, 교육 이수율 evidence를 수집함.

**결론 (2줄):**
- 기술사 판단: 대형·공공·다조직 개발은 CMMI로 프로세스를 제도화하고, 소규모 애자일 조직은 핵심 process area와 지표만 선택 적용함.
- 향후 방향: CMMI는 DevOps, Agile, DORA 지표와 결합해 문서 중심 평가에서 지속적 흐름 기반 개선 체계로 이동함.
