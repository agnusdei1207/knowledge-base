## Ⅰ. 개요
- **정의**: 사용자 관점의 기능 요구사항을 정량화하여 SW 규모를 측정하는 기법임
- **배경/필요성**: LOC 기반 측정은 언어 의존적이므로 기술 독립적인 규모 척도가 필요함
- **비유**: 건물 크기를 벽돌 수가 아닌 방 개수와 용도로 측정하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| FP 산정 절차와 기능 유형 분류 | 5가지 기능 유형, 미조정/조정 FP 구분 | 데이터 기능과 트랜잭션 기능 혼동 금지 |

> 요약: 사용자 기능 관점에서 기술 독립적으로 SW 규모를 측정하는 기법임

## Ⅱ. 구성요소
```text
[FP 기능 유형]
  데이터 기능 ---+--- ILF (내부 논리 파일)
                +--- EIF (외부 연계 파일)
  트랜잭션 기능 -+--- EI (외부 입력)
                +--- EO (외부 출력)
                +--- EQ (외부 조회)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| ILF | 시스템이 유지 관리하는 내부 데이터 그룹임 | 자체 창고 |
| EIF | 참조만 하는 외부 시스템의 데이터 그룹임 | 외부 도서관 |
| EI/EO/EQ | 데이터 입력/가공출력/단순조회 트랜잭션임 | 입금/명세서/잔액조회 |

> 요약: 데이터 기능(ILF, EIF)과 트랜잭션 기능(EI, EO, EQ) 5가지로 구성됨

## Ⅲ. 절차
```text
기능 식별 --> 복잡도 평가 --> 미조정 FP 산출 --> 조정 FP 산출
```
- 1단계: 기능 식별 — 요구사항에서 5가지 기능 유형별 항목을 도출함
- 2단계: 복잡도 평가 — 각 기능의 DET, RET/FTR 수로 저/중/고 복잡도를 판정함
- 3단계: 미조정 FP 산출 — 복잡도별 가중치를 적용하여 합산함
- 4단계: 조정 FP 산출 — 14개 일반 시스템 특성(GSC) 보정 계수를 곱하여 최종 FP를 산출함

> 요약: 식별-복잡도-미조정-조정 4단계로 FP를 산출함

## Ⅳ. 문제점
- 주관적 판정: 복잡도 등급 분류 시 측정자 간 편차가 발생함 — 결과 재현성 저하
- 비기능 미반영: 성능, 보안 등 비기능 요구사항이 규모에 충분히 반영되지 않음
- 신기술 한계: AI/데이터 파이프라인 등 비전통 기능에 대한 분류 기준이 모호함

> 요약: 주관성, 비기능 미반영, 신기술 한계가 FP 측정의 제약임

## Ⅴ. 개선방안
1. 단기: 측정 가이드라인을 상세화하고 측정자 교차 검증으로 편차를 최소화함
2. 중기: SNAP(Software Non-functional Assessment Process)을 병행하여 비기능 규모를 보완함
3. 장기: 신기술 유형별 기능 분류 체계를 확장하여 측정 범위를 넓힘

> 요약: 가이드 상세화-비기능 보완-분류 확장 순서로 FP 정확도를 개선함

## Ⅵ. 전망
- 발전 방향: COSMIC FP 등 차세대 측정법이 실시간/임베디드 영역까지 적용 범위를 확대하는 추세임
- 기술사적 판단: FP는 SW 예측(095 참조) 체계의 규모 입력값으로 지속적 역할을 수행함
- 기술사 제언: 조직 내 FP 측정 역량을 확보하고 실적 데이터와 연계하여 예측 정확도를 높일 필요
