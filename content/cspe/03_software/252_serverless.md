## Ⅰ. 개요
- 정의: 클라우드 제공자가 실행 인프라를 관리하고 이벤트 발생 시 함수와 관리형 서비스를 호출하는 설계 방식임
- 배경: 서버 프로비저닝·용량 계획 부담을 줄이고 호출량에 따라 실행 자원을 할당할 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 주요 개념 | FaaS, BaaS, Cold Start | 매우높음 |
| 패턴 | Event-driven, Fan-out | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ 이벤트 발생 ] -> [ 트리거 ] -> [ 함수 실행 (FaaS) ] -> [ 서비스 연계 ]
    (HTTP/S3)         (API GW)        (Lambda 등)         (DB/Push)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| FaaS | 실행 시점에만 인스턴스가 생성되는 함수 단위 서비스 | 1회용 컵 |
| BaaS | DB, 인증 등 외부 기능을 API로 제공받아 사용 | 완제품 반찬 |
| 트리거 | 함수를 실행시키는 특정 사건 (파일 업로드 등) | 스위치 |

> 요약: FaaS는 이벤트별 함수를 실행하고 BaaS는 인증·DB·메시징 기능을 API로 제공함

## Ⅲ. 주요 설계 패턴
- 4가지 핵심 패턴
1. 이벤트 기반 패턴: 데이터 상태 변화(S3 업로드 등)를 감지하여 비동기 처리함
2. 팬아웃 패턴: 하나의 이벤트를 여러 함수가 동시에 처리하여 병렬성 확보함
3. API 게이트웨이 패턴: HTTP 요청을 받아 적절한 함수로 라우팅하고 응답함
4. 오케스트레이션 패턴: Step Functions 등을 사용하여 여러 함수의 흐름을 제어함

> 요약: 이벤트·팬아웃·게이트웨이·오케스트레이션 패턴으로 함수 호출 관계와 상태 흐름을 구성함

## Ⅳ. 문제점
- 오랜 시간 실행되지 않다가 호출될 때 발생하는 지연 시간(Cold Start) 문제 있음
- 함수 단위로 분산되어 있어 시스템 전체의 흐름 파악 및 디버깅이 매우 어려움

## Ⅴ. 개선방안
- (단기) 프로비저닝된 동시성 기능을 사용하여 함수를 항상 준비 상태로 유지함
- (중기) 분산 트레이싱 도구(X-Ray 등)를 도입하여 가시성과 디버깅 능력 강화함
- (장기) 서버리스 환경에 최적화된 경량 런타임 및 프로그래밍 모델로 전환함

## Ⅵ. 전망
- 엣지 컴퓨팅과 결합하여 사용자 근처에서 초저지연으로 구동되는 'Edge FaaS' 확산됨
- 서버리스 DB 및 메시징 서비스의 고도화로 전 영역 서버리스화(No-Ops) 가속됨
