## Ⅰ. 개요
- 정의: 시스템 상태 변화(이벤트)를 생산하고 소비함으로써 동작하는 소프트웨어 구조임
- 배경: 생산자와 소비자의 실행 시점·처리 속도·배포 주기를 분리하고 비동기 상태 변화를 전달할 필요
- 출제 의도: 이벤트 브로커 활용 및 발행/구독(Pub/Sub) 모델 설계 역량 평가

## Ⅱ. 구성요소
- ASCII 구조도
  [Producer] --(Event)--> [Event Broker] --(Push/Pull)--> [Consumer]
                               |
                        [Topic/Channel]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 이벤트 브로커 | 이벤트의 수신, 저장, 전달을 담당하는 중개자 | 우체국 |
| 발행/구독 | 생산자와 소비자가 서로 몰라도 되는 통신 모델 | 신문 구독 |
| 이벤트 스트림 | 연속적으로 발생하는 이벤트의 흐름 | 강물 흐름 |
> 요약: 생산자와 소비자를 브로커를 통해 분리(Decoupling)하여 비동기 협력을 실현함

## Ⅲ. 절차
- ASCII 흐름도
  Event Define -> Broker Select -> Pub/Sub Design -> Error Handle
- 4단계 설명
1. Event Define: 비즈니스 의미를 갖는 핵심 상태 변화 사건들을 정의함
2. Broker Select: Kafka, RabbitMQ 등 용도에 맞는 메시지 미들웨어 선정함
3. Pub/Sub Design: 토픽 구조 및 메시지 스키마, 파티셔닝 전략 수립함
4. Error Handle: 메시지 유실 방지 및 재처리(DLQ), 멱등성 보장 설계함
> 요약: 이벤트를 정의하고 브로커를 통해 비동기 흐름과 예외 처리 체계를 구축함

## Ⅳ. 문제점
- 비동기 소비자가 늘어나면 사건의 전체 처리 경로를 추적하기 어렵고 파티션 간 순서를 보장할 수 없음

## Ⅴ. 개선방안
- 이벤트 카탈로그와 상관관계 ID로 흐름을 추적하고 순서가 필요한 사건은 같은 파티션 키로 배치함

## Ⅵ. 전망
- 실시간 스트림 프로세싱과 결합된 지능형 반응 시스템(Reactive) 고도화
- CSF: 이벤트의 의미론적 일관성과 유실 없는 신뢰성 있는 전달 보장이 설계의 핵심임
