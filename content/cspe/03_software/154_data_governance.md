# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 거버넌스를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 거버넌스는 **데이터 관리(Data Management)** 체계 중에서도 데이터의 **책임(ownership)**과 **표준**을 정하고, 그것을 **정책**으로 강제해 조직 전체가 같은 데이터를 같은 의미로 쓰게 만드는 통제 활동이다.
- **왜 필요한가**: 같은 "고객 수"가 부서마다 다르고, 개인정보 접근 권한이 불명확하며, 데이터 품질 문제의 책임자가 없으면 의사결정과 규제 대응이 흔들린다. 거버넌스는 이 책임 공백을 없앤다.
- **핵심 직관**: 데이터 조직의 교통법규다. 도로(파이프라인)가 아무리 많아도 신호·제한속도·책임자가 없으면 사고(지표 오류·정보 유출)가 난다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 데이터 관리(Data Management) | 데이터 자산을 계획·수집·저장·활용하는 전체 활동 — 거버넌스는 그중 "통제·책임" 부분 | 회사 경영 전체 중 준법감시 파트 |
| 거버넌스 위원회(council) | 원칙·우선순위·예외를 승인하는 최상위 의사결정체 | 이사회 |
| data owner | 특정 데이터 도메인(고객·상품 등)의 정의·품질·접근을 최종 책임지는 사람 | 부서장 |
| data steward | owner를 도와 표준 용어·품질 규칙을 실무에서 관리하는 실행자 | 팀 내 실무 담당자 |
| glossary(용어사전) | "고객"·"매출" 같은 핵심 용어의 조직 공통 정의 모음 | 사내 표준 용어집 |
| RACI | 업무별 책임자(R)·승인자(A)·자문(C)·통보(I)를 정하는 역할 분담표 | 프로젝트 역할 분담표 |
| PII 등급 | 개인정보 민감도에 따라 데이터를 분류하는 기준(예: 일반/민감/고유식별) | 문서 보안 등급(대외비·비밀) |
| 카탈로그 / IAM / 감사로그 | 정책을 실제로 실행하는 시스템: 자산 검색(카탈로그), 접근 승인(IAM), 이력 기록(감사로그) | 출입 명부·출입증·CCTV 녹화 |

## 깊이 이해

### 왜 거버넌스가 필요해졌나 (배경 — data swamp 문제)
빅데이터 플랫폼은 데이터를 대량으로 모으지만, 각 데이터에 정의·품질 기준·책임자가 없으면 "무엇이 정확한 값인지 아무도 모르는" 데이터 늪(data swamp)이 된다. 거버넌스는 owner·steward·표준 용어·품질 규칙·접근 정책·보존 정책을 정해, 데이터가 조직 내에서 항상 같은 의미로 해석되게 만드는 체계다.

### 조직이 어떻게 움직이나 (작동 원리)
거버넌스 위원회가 원칙과 정책을 정하면, 도메인별 data owner가 그 데이터에 대한 최종 책임을 지고, data steward가 owner를 도와 용어 정의와 품질 규칙을 실무에서 관리한다. 이 정책은 사람의 기억이 아니라 카탈로그(자산 등록 시 owner 필수 입력)·IAM(접근 신청 시 승인 워크플로)·품질 검사 도구(정의된 규칙을 파이프라인에서 자동 검사)에 내장돼야 실제로 지켜진다.

### 정책을 수치로 표현하면 — 구체 예시
"거버넌스가 잘 되고 있다"는 느낌이 아니라 숫자로 판단한다. 예를 들어 고객 데이터 100만 건에 대해 다음 기준을 둔다고 하자.
- owner 지정률 100% — 등록된 모든 핵심 데이터 자산에 담당자가 있어야 하며, 1건이라도 미지정이면 거버넌스가 뚫린 것이다.
- 결측률 0.5% 이하 — 100만 건 중 최대 5,000건까지만 허용, 5,001건째부터는 정책 위반으로 분류돼 owner에게 자동 알림이 간다.
- 중복률 1% 이하 — 100만 건 중 최대 10,000건까지 허용.
- 접근 승인 SLA 2일 — 신청 후 48시간 안에 승인·반려가 안 나면 자동으로 상위 결재자에게 에스컬레이션된다.
- 이렇게 임계값을 숫자로 못박아야 "정책이 문서로만 존재하는지, 실제로 지켜지는지"를 감사할 수 있다.

### 중앙 집중 vs 도메인 자율 — 판별 원리
모든 정책을 중앙 데이터팀이 결정하면 속도가 느리고 현업 맥락을 놓친다. 반대로 각 도메인 팀이 전부 자율로 관리하면 용어와 기준이 다시 흩어진다. 그래서 실무는 원칙·표준·감사 기준은 중앙(위원회)이 정하고, 실제 데이터 정의·품질 규칙 운영은 도메인 owner·steward가 맡는 "중앙 정책 + 도메인 실행" 혼합 모델을 쓴다. 판단 기준은 도메인 수(3개 이상이면 표준 통일 필요성이 커짐)와 데이터 민감도(개인정보 포함 시 중앙 통제 강화)다.

### 비유
병원의 진료 기록 관리와 같다. 기록 형식, 접근 권한, 보존 기간, 오류 정정 절차가 정해져 있어야 여러 의료진이 같은 환자 기록을 같은 방식으로 다루고, 사고가 나도 책임 소재와 감사 근거를 추적할 수 있다.

### 흔한 오해
거버넌스는 통제 문서를 작성하는 일이 아니다. 정책 문서만 있고 카탈로그·품질 검사·접근 제어·감사로그와 연결되지 않으면, 아무도 어기고 있는지조차 알 수 없는 "장식용 규정"에 그친다.

## 연결 개념
- 데이터 카탈로그 — 정책과 소유자 정보를 실제로 노출하는 도구
- 마스터 데이터 관리 — 거버넌스가 지정한 핵심 기준 데이터의 정합성 관리
- 데이터 품질 관리 — 거버넌스가 정한 기준을 정량 지표로 검증하는 실행 수단

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 거버넌스 답안은 조직, 정책, 프로세스, 도구, 지표를 분리해 책임과 실행 수단을 명확히 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 거버넌스는 데이터 자산의 책임, 표준, 품질, 접근, 보존을 조직과 시스템으로 통제하는 체계임.
> 2. **가치**: 지표 불일치, 개인정보 노출, 품질 사고를 owner, 정책, 감사로그, 품질 지표로 관리함.
> 3. **판단 포인트**: 중앙 집중 정책과 도메인 자율 운영의 균형을 데이터 민감도와 변경 빈도로 정해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 관리 체계 설계 확인 | owner, steward, council 역할 | 조직 역할 누락 |
| 정책 실행 수단 확인 | 카탈로그, 품질 규칙, 접근 제어, 감사로그 | 원칙 선언만 작성 |
| 정량 지표 판단 확인 | 결측률, 중복률, 승인 SLA, PII 태그율 | 효과를 감상적으로 서술 |

> 요약: 데이터 거버넌스는 조직 규정과 플랫폼 통제가 연결되어야 답안 완성도가 올라감.

## Ⅰ. 개요 및 필요성

- 개요: 데이터 거버넌스는 데이터 책임과 기준의 통제 체계임.
- 배경: 조직 내 데이터가 증가하면 지표 의미 불일치, 품질 저하, 권한 오남용이 발생한다.
- 필요성: 정책과 실행 도구를 연결해 데이터 품질 기준, 접근권한, 규제 대응 절차를 일관되게 적용한다.

---

## Ⅱ. 구조 및 구성요소

```text
Governance Council -> Data Owner/Steward -> Policy/Standard -> Catalog/Quality/Access -> Audit
                                    +-> Domain Data Team
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 위원회 | 원칙, 우선순위, 예외 승인 | CDO, 보안, 법무 참여 |
| 오너/스튜어드 | 데이터 책임, 용어, 품질 규칙 관리 | domain별 R&R |
| 정책/표준 | 용어, 품질, 접근, 보존 기준 | ISO/IEC 38505, DAMA 참조 |
| 실행 도구 | 카탈로그, DQ, IAM, 감사로그 | 자동 검증과 승인 연계 |

> 요약: 거버넌스는 의사결정 조직, 책임자, 정책, 실행 도구가 연결된 운영 체계임.

---

## Ⅲ. 동작원리 및 흐름도

```text
정책 수립 -> 데이터 분류 -> 품질/권한 규칙 적용 -> 사용 승인 -> 감사/개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 핵심 데이터와 책임자 지정 | owner 지정률 100% |
| 2 | 표준 용어와 민감도 등급 정의 | glossary 중복률 5% 이하 |
| 3 | 품질 규칙과 접근 정책 적용 | 결측률, PII 태그율 |
| 4 | 사용 신청, 승인, 감사로그 기록 | 승인 SLA 2일 이하 |
| 5 | 위반 사례와 지표 개선 | 월간 이슈 처리율 95% |

> 요약: 거버넌스는 정책 수립에서 끝나지 않고 분류, 규칙 적용, 승인, 감사까지 반복됨.

| 정책 미적용 | 도구 미연계 | 카탈로그/IAM/DQ 자동 연계 | 정책 적용률 95% 이상 |

> 요약: 거버넌스 리스크는 형식화와 현업 저항이며 위험 등급 기반 자동화로 완화함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 책임 | 핵심 데이터 owner 100% | 카탈로그 필수값 검사 |

| 접근 | 승인 SLA 2일 이하, 위반 0건 | IAM, 감사로그 |

> 요약: 책임, 품질, 접근 지표를 동시에 관리해야 거버넌스 실행 여부를 판단할 수 있음.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 조직 설계: CDO 산하 council, domain owner, data steward를 지정하고 핵심 데이터 100개부터 RACI 적용
2. 정책 자동화: 카탈로그 owner 필수값, PII 태그, IAM 승인, DQ rule을 CI/CD와 배치 작업에 연결
3. 지표 운영: 결측률 0.5%, 중복률 1%, 승인 SLA 2일, 감사로그 보존 1년을 월간 대시보드로 점검

**결론 (2줄):**
- 기술사 판단: 규제 데이터와 전사 지표가 많으면 중앙 정책+도메인 책임 모델, 소규모 분석은 핵심 자산 중심으로 단계 적용함
- 향후 방향: 데이터 제품, 데이터 계약, AI 학습 데이터 통제와 결합되어 플랫폼 운영의 기본 원칙이 됨
