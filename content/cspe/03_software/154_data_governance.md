## 미리 알고가기

- 데이터 거버넌스는 데이터 사용·보호·품질에 관한 의사결정권·책임·정책을 정하는 체계임
- Data Owner는 데이터의 사용 목적·품질 기준·접근 승인과 우선순위를 책임짐
- Data Steward는 정의·표준·품질 규칙·메타데이터를 운영하고 위반을 조정함
- 중요 데이터 요소(CDE)는 업무·규제·위험에 직접 영향을 주어 우선 관리하는 데이터 항목임
- 정책은 지켜야 할 원칙을 정하고 표준은 공통 구현 기준을, 통제는 실제 준수 여부를 검사함
- 데이터 관리는 거버넌스가 정한 정책을 수집·저장·품질·보안 작업으로 실행함

## 작성 근거(검토용)

- 거버넌스는 의사결정권·Owner·Steward·정책·표준·통제·측정이라는 책임 구조를 핵심으로 선정함
- 비교표는 거버넌스와 데이터 관리의 목적·책임·산출물·활동·측정·관계를 같은 기준에서 대비함
- 순서보다 역할과 의사결정 구조가 핵심이므로 독립 Ⅴ절을 두지 않고 구성요소 관계로 완결함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 정책 수립과 기술 실행을 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 거버넌스는 가치·위험·규제 요구에 따라 데이터 결정권과 Owner·Steward 책임, 정책·표준·통제 기준을 정하는 체계임
- **배경/필요성**: 부서별 데이터 정의·품질·접근 판단의 불일치를 줄이고 데이터 수명주기 전반의 책임을 확인하기 위해 공통 의사결정 구조가 필요함

## Ⅱ. 특징

- 경영 목표와 규제 위험을 기준으로 중요 데이터 요소와 관리 우선순위를 정함
- Owner가 데이터 사용·품질·접근 결정을 책임지고 Steward가 정의·규칙·메타데이터를 운영함
- 정책·표준을 카탈로그·품질 규칙·접근 제어·보존 정책의 실행 가능한 통제로 연결함
- 도메인별 책임과 전사 공통 용어·식별자·분류 기준을 함께 관리함
- 정책 준수율·품질 규칙 통과율·미소유 자산 수를 측정해 책임과 통제의 공백을 찾음

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 거버넌스 | 데이터 관리 |
|:---|:---|:---|
| 목적 | 데이터 사용·보호의 결정권과 책임 설정 | 정책에 따라 데이터 수명주기 작업 수행 |
| 책임 주체 | 위원회·Owner·Steward | 아키텍트·엔지니어·DBA·보안 담당자 |
| 주요 산출물 | 정책·표준·역할·CDE·판정 기준 | 모델·파이프라인·카탈로그·품질 결과·접근 설정 |
| 주요 활동 | 우선순위·예외 승인·책임 조정 | 수집·저장·정제·보호·폐기 실행 |
| 측정 기준 | 정책 적용률·책임 배정률 | 품질 통과율·접근 오류율 |
| 상호 관계 | 무엇을 누가 결정할지 정의 | 결정된 기준을 시스템과 절차로 실행 |

> 요약: 데이터 거버넌스는 결정권·책임·정책을 정하고 데이터 관리는 이를 시스템과 운영 작업으로 실행함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Governance Council | 전사 목표·위험·규제에 따라 정책과 우선순위·예외를 승인함 |
| Data Owner | 도메인 데이터의 사용 목적·품질 기준·접근과 투자 우선순위를 결정함 |
| Data Steward | 업무 용어·표준·품질 규칙·분류와 이슈 조정을 수행함 |
| Policy·Standard·Control | 원칙을 공통 구현 기준과 자동·수동 검사로 구체화함 |
| Catalog·Quality·Security Platform | 소유권·계보·품질·접근·보존 통제를 시스템에 적용함 |
| Metric·Issue Workflow | 위반·예외·품질 결과를 책임자에게 배정하고 조치 이력을 관리함 |

```text
Governance Council -> Policy·Standard -> Platform Control
          |                                    |
     Owner·Steward <----- Metric·Issue --------+
```

> 요약: 위원회와 Owner·Steward가 정한 정책을 플랫폼 통제로 집행하고 측정·이슈를 책임 구조로 되돌림.

## Ⅵ. 실무 사례

1. 고객 ID 거버넌스는 Owner와 표준 키를 지정하고 미매핑 레코드 수·품질 규칙 통과율을 확인함
2. 민감 데이터 관리는 분류별 접근·보존 정책을 적용하고 미분류 열 수·정책 위반 건수를 확인함

## Ⅶ. 결론

- 데이터 거버넌스는 중요 데이터 범위·결정권·실행 가능한 통제·책임 지표와 예외 처리 기준으로 운영해야 함
