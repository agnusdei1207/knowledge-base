## 미리 알고가기

- 데이터 거버넌스는 데이터 사용·보호·품질에 관한 의사결정권·책임·정책을 정하는 체계임
- Data Owner는 데이터의 사용 목적·품질 기준·접근 승인과 우선순위를 책임짐
- Data Steward는 정의·표준·품질 규칙·메타데이터를 운영하고 위반을 조정함
- 중요 데이터 요소(CDE)는 업무·규제·위험에 직접 영향을 주어 우선 관리하는 데이터 항목임
- 정책은 지켜야 할 원칙을 정하고 표준은 공통 구현 기준을, 통제는 실제 준수 여부를 검사함
- 데이터 관리는 거버넌스가 정한 정책을 수집·저장·품질·보안 작업으로 실행함

## 작성 근거(검토용)

- 거버넌스는 의사결정권·Owner·Steward·정책·표준·통제·측정이라는 책임 구조를 핵심으로 선정함
- 비교표는 거버넌스와 데이터 관리의 목적·책임 주체·활동·산출물·측정 기준을 같은 기준에서 대비함
- Ⅴ절은 중요 데이터 선정부터 책임 배정·정책 구체화·통제 집행·위반 개선까지의 운영 순환으로 구성함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 정책 수립과 기술 실행을 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 거버넌스는 가치·위험·규제 요구에 따라 데이터 결정권과 Owner·Steward 책임, 정책·표준·통제 기준을 정하는 체계임
- **배경/필요성**: 부서별 데이터 정의·품질·접근 판단의 불일치를 줄이고 데이터 수명주기 전반의 책임을 확인하기 위해 공통 의사결정 구조가 필요함

### 쉽게 이해하기 (학습용)
- 데이터의 사용·보호 결정을 누가 내리고 누가 실행·설명할지 정하는 책임 체계임

## Ⅱ. 특징

- 경영 목표와 규제 위험을 기준으로 중요 데이터 요소와 관리 우선순위를 정함
- Owner가 데이터 사용·품질·접근 결정을 책임지고 Steward가 정의·규칙·메타데이터를 운영함
- 정책·표준을 카탈로그·품질 규칙·접근 제어·보존 정책의 실행 가능한 통제로 연결함
- 도메인별 책임과 전사 공통 용어·식별자·분류 기준을 함께 관리함
- 정책 준수율·품질 규칙 통과율·미소유 자산 수를 측정해 책임과 통제의 공백을 찾음

### 쉽게 이해하기 (학습용)
- 회의와 문서만으로 끝나면 통제가 아니며 시스템 검사와 책임 지표로 이어져야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 거버넌스 | 데이터 관리 |
|:---|:---|:---|
| 목적·책임 주체 | 위원회·Owner·Steward가 데이터 사용·보호의 결정권과 책임을 설정 | 아키텍트·엔지니어·DBA·보안 담당자가 정책에 따라 수명주기 작업을 수행 |
| 주요 활동·산출물 | 우선순위·예외 승인·책임 조정으로 정책·표준·CDE·판정 기준을 산출 | 수집·저장·정제·보호·폐기를 실행해 모델·파이프라인·카탈로그·품질 결과·접근 설정을 산출 |
| 측정 기준 | 정책 적용률·책임 배정률 | 품질 통과율·접근 오류율 |

> 요약: 데이터 거버넌스는 결정권·책임·정책을 정하고 데이터 관리는 이를 시스템과 운영 작업으로 실행함.

### 쉽게 이해하기 (학습용)
- 거버넌스는 규칙과 책임을 결정하고 데이터 관리는 실제 수집·저장·품질·보호 작업을 수행함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 거버넌스 위원회 | 전사 목표·위험·규제에 따라 정책과 우선순위·예외를 승인함 |
| Data Owner | 도메인 데이터의 사용 목적·품질 기준·접근과 투자 우선순위를 결정함 |
| Data Steward | 업무 용어·표준·품질 규칙·분류와 이슈 조정을 수행함 |
| 정책·표준·통제 | 원칙을 공통 구현 기준과 자동·수동 검사로 구체화함 |
| 카탈로그·품질·보안 플랫폼 | 소유권·계보·품질·접근·보존 통제를 시스템에 적용함 |
| 지표·이슈 처리 흐름 | 위반·예외·품질 결과를 책임자에게 배정하고 조치 이력을 관리함 |

```text
거버넌스 위원회 -> 정책·표준 -> 플랫폼 통제
          |                                    |
     Owner·Steward <------ 지표·이슈 ----------+
```

> 요약: 위원회와 Owner·Steward가 정한 정책을 플랫폼 통제로 집행하고 측정·이슈를 책임 구조로 되돌림.

### 쉽게 이해하기 (학습용)
- 위원회, 데이터 책임자·관리자, 정책과 기술 통제, 위반 처리 흐름으로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
[중요 데이터·위험 선정] -> [Owner·Steward 책임 배정] -> [정책·표준 정의]
        -> [플랫폼 통제 집행] -> [지표·위반 검토] -> [예외·정책 개선]
```

1. 규제·위험·사업 가치로 중요 데이터와 우선 통제 범위를 정함
2. 결정권자와 업무·기술 실행 책임을 Owner·Steward·운영자에게 배정함
3. 정책을 품질 규칙·접근 제어·보존 기간과 승인 기준으로 구체화함
4. 적용률·위반·예외·조치 시간을 검토해 통제와 정책을 개선함

> 요약: 책임자가 정한 정책을 시스템 통제로 집행하고 위반·예외 결과를 다시 의사결정에 반영함.

### 쉽게 이해하기 (학습용)
- 중요한 장부의 주인과 검사 규칙을 정하고 실제 위반 결과로 규칙을 고치는 순환임

## Ⅵ. 실무 사례

1. 고객 ID 거버넌스는 Owner와 표준 키를 지정하고 미매핑 레코드 수·품질 규칙 통과율을 확인함
2. 민감 데이터 관리는 분류별 접근·보존 정책을 적용하고 미분류 열 수·정책 위반 건수를 확인함

### 쉽게 이해하기 (학습용)
- 개인정보·핵심 지표에서 책임 배정률·정책 적용률·예외 만료·위반 조치 시간을 확인함

## Ⅶ. 결론

- 데이터 거버넌스는 중요 데이터 범위·결정권·실행 가능한 통제·책임 지표·예외 처리 절차를 기준으로 운영해야 함
- 전사 일괄 통제보다 위험 기반 우선순위와 자동 집행 가능한 정책부터 적용해 책임 공백을 줄여야 함

### 쉽게 이해하기 (학습용)
- 모든 장부를 한꺼번에 규제하기보다 중요한 장부부터 주인과 자동 검사를 분명히 함
