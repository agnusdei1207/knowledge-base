## 미리 알고가기

- 단위 테스트는 함수나 클래스처럼 작은 코드 단위를 검증하는 테스트임
- 통합 테스트는 여러 모듈이나 서비스가 연결될 때 생기는 오류를 검증하는 테스트임
- 인수 테스트는 사용자나 발주자가 요구를 받아들일 수 있는지 최종 판단하는 테스트임

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 테스트는 코드와 컴포넌트와 시스템과 사용자 요구 수준에서 기능과 품질을 검증해 결함과 위험을 찾는 활동이며, 범위에 따라 단위와 통합과 시스템과 인수 테스트로 나뉨.
- **배경/필요성**: 결함은 코드 내부와 모듈 연결과 전체 운영과 사용자 요구 수준에서 서로 다르게 나타나므로, 하나의 테스트만으로는 품질 위험을 충분히 줄일 수 없어 레벨별 역할 분담이 필요함.

## Ⅱ. 특징

- 단위 테스트는 가장 빠르고 국소적인 결함 탐지에 유리함
- 통합 테스트는 인터페이스와 데이터 흐름 문제를 검증함
- 시스템 테스트는 비기능을 포함한 전체 동작을 확인함
- 인수 테스트는 사용자와 계약 관점에서 최종 수용 여부를 판단함

## Ⅲ. 종류 및 비교

| 구분 | 단위 테스트 | 통합 테스트 | 시스템 테스트 | 인수 테스트 |
|:---|:---|:---|:---|:---|
| 검증 범위 | 함수와 클래스 같은 작은 코드 단위를 검증함 | 모듈과 서비스가 연결될 때의 상호작용을 검증함 | 전체 시스템이 요구대로 동작하는지 검증함 | 사용자나 발주자가 요구를 받아들일 수 있는지 검증함 |
| 장점 | 빠른 실행으로 회귀 결함을 빨리 찾기 좋음 | 인터페이스 오류와 데이터 전달 문제를 찾기 좋음 | 기능과 성능과 운영 조건을 함께 확인하기 좋음 | 실제 업무 적합성과 계약 충족 여부를 확인하기 좋음 |
| 주된 한계 | 외부 연동과 전체 흐름 문제는 직접 찾기 어려움 | 환경 구성 비용이 커지고 실패 원인 분리가 어려울 수 있음 | 실행이 느리고 유지비가 큼 | 시점이 늦으면 수정 비용이 급격히 커질 수 있음 |
| 핵심 질문 | 코드가 맞는가 | 연결이 맞는가 | 시스템이 동작하는가 | 사용자가 받아들일 수 있는가 |

> 요약: 테스트 종류는 많을수록 좋은 것이 아니라 서로 다른 위험을 중복 없이 나눠 맡게 해야 함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 테스트 범위 계층 | 각 테스트 레벨이 다른 위험을 맡아 전체 품질망을 형성함 |
| 테스트 환경 | 레벨별로 실환경 비중과 모의 환경 비중이 달라 신뢰도와 비용을 좌우함 |
| 기대 결과 기준 | 기대 결과가 명확해야 자동화와 회귀 검증이 가능해짐 |
| 결함 피드백 순환 | 발견 결함이 원인 단계로 빨리 돌아가야 테스트 비용 대비 효과가 커짐 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 범위 선정      | --> | 테스트 설계    | --> | 실행/결함 수집 | --> | 수정/회귀 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **범위 선정**: 어떤 레벨에서 어떤 위험을 검증할지 정함
2. **테스트 설계**: 입력과 기대 결과와 환경을 정의함
3. **실행 및 결함 수집**: 테스트를 수행하고 실패 원인을 기록함
4. **수정 및 회귀 검증**: 결함 수정 후 관련 테스트를 다시 수행함

## Ⅵ. 실무 적용 및 유의점

1. 백엔드와 플랫폼 개발에서는 단위 테스트와 통합 테스트의 역할을 섞지 않는 것이 중요하므로 단위 테스트는 빠른 회귀 검증에 집중하고 통합 테스트는 외부 연동에 집중하며 테스트 분포와 전체 실행 시간으로 확인함
2. 고객 검수형 프로젝트에서는 인수 테스트를 말기에만 몰아두면 요구 불일치가 크게 터지므로 수용 기준을 초기에 시나리오로 정리하고 인수 단계 결함 발견 시점과 재작업 비율로 확인함

## Ⅶ. 결론

소프트웨어 테스트의 본질은 테스트를 많이 만드는 데 있지 않고 각 레벨이 서로 다른 위험을 나눠 맡게 만드는 데 있음.
