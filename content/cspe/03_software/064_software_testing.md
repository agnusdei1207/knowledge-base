## 미리 알고가기

- 단위 테스트는 함수나 클래스처럼 작은 코드 단위를 검증하는 테스트임
- 통합 테스트는 여러 모듈이나 서비스가 연결될 때 생기는 오류를 검증하는 테스트임
- 인수 테스트는 사용자나 발주자가 요구를 받아들일 수 있는지 최종 판단하는 테스트임

## 작성 근거(검토용)

- 소프트웨어 테스트는 검증 범위, 발견 결함, 실행 부담, 판정 질문을 핵심 비교축으로 선정함
- 구성은 테스트 레벨별 범위·환경·기대 결과·결함 피드백의 관계를 중심으로 제시함
- 실무 판단은 레벨별 테스트 분포, 전체 실행시간, 인수 결함률, 재작업률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 테스트는 코드·컴포넌트·시스템·사용자 요구 수준에서 기능과 품질을 검증해 결함과 위험을 찾는 활동임
- **배경/필요성**: 코드 내부·모듈 연결·전체 시스템·사용자 요구에서 발생하는 결함이 다르므로 테스트 레벨별 검증이 필요함

## Ⅱ. 특징

- 단위 테스트는 외부 연동을 대역으로 분리하고 함수·클래스 범위의 결과와 분기를 검증함
- 통합 테스트는 인터페이스와 데이터 흐름 문제를 검증함
- 시스템 테스트는 비기능을 포함한 전체 동작을 확인함
- 인수 테스트는 사용자와 계약 관점에서 최종 수용 여부를 판단함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단위 테스트 | 통합 테스트 | 시스템 테스트 | 인수 테스트 |
|:---|:---|:---|:---|:---|
| 검증 범위 | 함수·클래스 | 모듈·서비스 연동 | 전체 시스템 | 사용자·발주자 요구 |
| 발견 결함 | 함수·클래스의 계산·분기 오류 | 모듈·서비스 계약과 데이터 전달 오류 | 전체 기능·성능·운영 환경 오류 | 업무 시나리오·계약 수용 기준 불일치 |
| 주된 한계 | 외부 연동 결함 탐지 한계 | 환경 구성과 원인 분리 부담 | 긴 실행시간과 유지비 | 늦은 발견에 따른 재작업 비용 |
| 핵심 질문 | 코드가 맞는가 | 연결이 맞는가 | 시스템이 동작하는가 | 사용자가 받아들일 수 있는가 |

> 요약: 코드 결함은 단위, 연결 오류는 통합, 전체 품질은 시스템, 업무 수용 여부는 인수 테스트로 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 테스트 범위 계층 | 코드·연동·시스템·사용자 요구의 검증 범위를 나눔 |
| 테스트 환경 | 레벨별로 실환경 비중과 모의 환경 비중이 달라 신뢰도와 비용을 좌우함 |
| 기대 결과 기준 | 기대 결과가 명확해야 자동화와 회귀 검증이 가능해짐 |
| 결함 피드백 순환 | 발견 결함을 원인 코드와 관련 회귀 테스트에 연결함 |

> 요약: 테스트 범위에 맞는 환경과 기대 결과를 정의하고 발견 결함을 원인 단계의 수정·회귀 검증으로 연결함.

## Ⅵ. 실무 사례

1. 백엔드는 단위 테스트와 외부 연동 통합 테스트를 분리하고 레벨별 테스트 분포·실행시간을 확인함
2. 고객 검수 프로젝트는 수용 기준을 시나리오로 작성하고 인수 결함률·재작업률을 확인함

## Ⅶ. 결론

소프트웨어 테스트는 단위·통합·시스템·인수 레벨이 서로 다른 품질 위험을 나눠 검증하는 활동임
