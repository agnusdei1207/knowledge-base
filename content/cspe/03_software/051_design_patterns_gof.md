## 미리 알고가기

- GoF 디자인 패턴은 객체지향 설계 문제를 생성, 구조, 행위 관점으로 정리한 패턴 모음임
- Variation point는 요구 변화가 집중되는 지점을 뜻함
- Pattern intent는 패턴이 해결하려는 문제와 적용 이유를 뜻함

## 작성 근거(검토용)

- GoF 패턴은 해결 문제, 변경 분리 대상, 구조상 부담을 핵심 비교축으로 선정함
- 구성은 패턴 의도, 참여 역할, 변경 지점, 상충 관계를 중심으로 제시함
- 실무 판단은 변경 영향 범위, 추상화 계층 수, 연동 구현 중복률로 구체화함

## Ⅰ. 개요

- **정의/개념**: GoF 디자인 패턴은 반복되는 객체 생성·구조·행위 문제를 재사용 가능한 역할과 협력 구조로 정리한 23개 패턴임
- **배경/필요성**: 반복 설계 문제에 맞는 객체 역할과 협력 구조를 선택하고 이를 공통 언어로 공유할 기준이 필요함

## Ⅱ. 특징

- 구체 코드보다 객체 역할과 협력 구조를 재사용함
- 생성, 구조, 행위 문제를 분리해 선택 맥락을 제공함
- 패턴 이름으로 반복 문제, 참여 객체, 책임 협력 구조를 공통 용어로 공유함
- 문제에 맞지 않게 적용하면 계층과 추상화만 늘어날 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 생성 패턴 | 구조 패턴 | 행위 패턴 |
|:---|:---|:---|:---|
| 다루는 문제 | 객체를 어떤 방식으로 만들지에 초점을 둠 | 클래스와 객체를 어떻게 조합할지에 초점을 둠 | 객체가 책임을 어떻게 나누고 협력할지에 초점을 둠 |
| 대표 예시 | Factory Method·Builder | Adapter·Decorator | Strategy·Observer |
| 변경 분리 | 객체 생성 책임과 사용 책임 분리 | 기존 객체와 새 인터페이스·책임 연결 | 교체할 알고리즘·통지·요청을 객체로 분리 |
| 주의할 점 | 단순 생성에 적용하면 계층만 늘어남 | 래퍼 계층 증가 | 객체 간 흐름 추적 부담 |

> 요약: 객체 생성은 생성 패턴, 객체 조합은 구조 패턴, 책임과 협력은 행위 패턴으로 분리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 패턴 의도 | 해결할 문제와 적용 조건을 명시해 패턴 선택 기준을 제공함 |
| 역할 협력 | 참여 객체의 역할·책임·호출 관계를 정의함 |
| 변경 지점 | 자주 바뀌는 생성·구조·행위를 식별해 분리 대상을 정함 |
| 상충 관계 | 유연성 증가와 추상화 복잡도 증가를 함께 평가함 |

> 요약: 패턴 의도로 문제를 한정하고 역할 협력으로 변경 지점을 분리한 뒤 복잡도 증가를 검토함.

## Ⅵ. 실무 사례

1. 결제 수단 모듈은 Strategy로 처리 규칙을 분리하고 변경 영향 범위·추상화 계층 수를 확인함
2. 외부 API 연동은 Adapter로 인터페이스를 통일하고 연동 구현 중복률·수정 범위를 확인함

## Ⅶ. 결론

GoF 패턴은 반복되는 생성·구조·행위 문제의 변경 지점에 맞는 협력 구조를 선택하는 설계 기준임
