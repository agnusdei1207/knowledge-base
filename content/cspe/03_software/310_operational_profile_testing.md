# 📖 【암기용】 개념 완전 이해

> 목적: 운영 프로파일 기반 테스트를 처음 봐도 실제 사용 비율로 테스트하는 이유를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 실제 운영 사용 시나리오와 빈도 분포를 기준으로 테스트 케이스와 부하를 설계하는 기법
- **왜 필요한가**: 모든 기능을 같은 비중으로 테스트하면 사용자가 자주 쓰는 경로의 장애 가능성을 충분히 낮추지 못함
- **핵심 직관**: 시험 범위가 아니라 실제 출제 빈도에 맞춰 공부하듯, 테스트도 실제 사용 빈도에 맞춰 자원을 배분함

## 깊이 이해
- **배경·문제의식**: 기능 명세 기반 테스트는 기능 존재 여부를 확인하지만 운영 신뢰도를 충분히 설명하지 못함. 로그인, 조회, 결제처럼 사용 빈도가 높은 경로는 작은 결함도 장애 건수를 크게 만든다.
- **작동 원리**: 로그, APM, 비즈니스 이벤트에서 사용 시나리오와 발생 확률을 추출함. 확률이 높은 시나리오에 테스트 케이스, 부하, 신뢰도 검증 자원을 더 배정함.
- **비유**: 지하철 안전 점검에서 하루 10명 쓰는 출구와 10만 명 쓰는 환승 통로를 같은 횟수로 점검하지 않는 것과 같음.
- **구체 예시**: 쇼핑몰 트래픽이 상품조회 70%, 장바구니 20%, 결제 10%이면 부하 테스트도 이 비율로 구성하고 결제는 오류율 0.01% 이하 별도 기준을 둠.
- **흔한 오해·주의점**: 사용 빈도가 낮은 기능을 버리는 것이 아님. 법규·보안·결제처럼 영향도가 큰 기능은 빈도와 별도로 위험 가중치를 부여해야 함.

## 연결 개념
- Reliability Growth Testing: 신뢰도 성장 측정
- Usage-Based Testing: 사용 빈도 기반 테스트 설계
- SRE SLO: 사용자 영향 기준 품질 목표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 운영 프로파일 기반 테스트는 실제 사용 빈도와 업무 영향도를 반영한 테스트 우선순위로 답한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 운영 프로파일 기반 테스트는 실제 운영 시나리오와 발생 확률을 모델링해 테스트 케이스·부하·신뢰도 검증 비중을 배분하는 기법이다.
> 2. **가치**: 사용자에게 많이 노출되는 경로의 결함 발견 확률을 높여 운영 장애 건수와 오류 예산 소모를 줄인다.
> 3. **판단 포인트**: 빈도만 보지 말고 결제·보안·규제 기능처럼 영향도가 큰 경로에는 위험 가중치를 추가한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 테스트 우선순위 설계 확인 | 운영 시나리오, 사용 확률, 위험 가중치 | 기능 목록을 균등 테스트한다고 서술 |
| 신뢰도 평가 이해 확인 | 사용 빈도 기반 결함 발견, reliability estimate | 단순 커버리지와 동일시 |
| 운영 데이터 활용 확인 | 로그, APM, 이벤트, SLO | 운영 데이터 품질과 갱신 주기 누락 |

> 요약: 이 문제는 실제 사용 확률과 영향도를 반영해 테스트 자원을 배분하는 능력을 요구한다.

---

## Ⅰ. 개요 및 필요성

운영 프로파일 기반 테스트는 실제 사용 빈도에 맞춘 테스트 설계 기법이다. 기능 수 기준 균등 테스트는 사용자 영향이 큰 경로를 충분히 검증하지 못함. 운영 로그와 이벤트를 이용해 시나리오 확률을 모델링하고 테스트 비중을 조정해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Operation Log -> Scenario Mining -> Probability Model -> Test Design -> Execution -> Reliability Report
  / Risk Weight
  / SLO
  / Feedback
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 운영 데이터 | 실제 사용자 행동 수집 | 로그, APM, clickstream |
| 운영 프로파일 | 시나리오별 발생 확률 모델 | 조회 70%, 장바구니 20%, 결제 10% |
| 테스트 설계 | 확률·위험 기반 케이스 배분 | 경계값·오류 경로 포함 |
| 신뢰도 리포트 | 결함률·MTBF·SLO 영향 분석 | 릴리스 승인 근거 |

> 요약: 운영 데이터에서 확률 모델을 만들고 테스트 설계와 신뢰도 보고서로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
로그 수집 -> 시나리오 분류 -> 발생 확률 산정 -> 위험 가중치 적용 -> 테스트 실행 -> 프로파일 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 운영 로그·이벤트 수집 | 표본 기간 2~4주 |
| 2 | 사용자 시나리오 분류 | 상위 20개 경로 80% 커버 |
| 3 | 발생 확률·위험 가중치 산정 | 빈도×업무 영향도 |
| 4 | 테스트 케이스·부하 배분 | 프로파일 오차 5%p 이하 |
| 5 | 결함·신뢰도 분석 후 갱신 | 결함 밀도, MTBF, SLO |

> 요약: 운영 프로파일은 로그 기반 확률 산정, 위험 보정, 테스트 실행, 갱신의 반복 절차로 운영된다.

---

## Ⅳ. 특징

| 구분 | 명세 기반 균등 테스트 | 운영 프로파일 기반 테스트 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 우선순위 | 기능 수 기준 | 사용 확률·위험 기준 | 상위 경로 80% 커버 |
| 부하 모델 | 임의 TPS | 실제 트래픽 분포 | 조회 70%, 결제 10% |
| 신뢰도 | 테스트 통과율 | 사용자 노출 결함률 | escaped defect rate |
| 갱신 | 릴리스 전 1회 | 운영 로그 기반 주기 갱신 | 월 1회 프로파일 보정 |

> 요약: 운영 프로파일 기반 테스트는 실제 사용 분포로 테스트 자원을 배분해 사용자 영향 결함을 줄이는 방식이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 기능 테스트 | 요구사항별 균등 | 사용 빈도 기반 | 운영 로그 확보 가능 |
| 부하 테스트 | 고정 TPS | 트랜잭션 mix 반영 | 트래픽 패턴 변동 큰 서비스 |
| 위험 기반 테스트 | 영향도 중심 | 빈도+영향도 결합 | 결제·인증 등 고위험 경로 |

> 요약: 운영 프로파일은 운영 데이터가 있고 사용자 행동 분포가 품질에 직접 영향을 줄 때 적용 가치가 크다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 프로파일 왜곡 | 짧은 표본 기간 | 2~4주 로그, 시즌 보정 | 프로파일 오차 5%p 이하 |
| 저빈도 고위험 누락 | 빈도만 반영 | 위험 가중치, 규제 케이스 필수화 | 고위험 케이스 커버 100% |
| 데이터 품질 저하 | 로그 누락·중복 | 이벤트 스키마 검증 | invalid event rate 0.1% 이하 |

> 요약: 표본 왜곡, 저빈도 고위험 누락, 로그 품질 문제를 보정해야 테스트 우선순위가 타당하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 커버리지 | 상위 사용자 경로 80% 이상 | 로그 기반 path 분석 |
| 신뢰도 | escaped defect 0.1% 이하 | 운영 결함 분석 |
| 부하 재현성 | transaction mix 오차 5%p 이하 | 부하 테스트 리포트 |

> 요약: 적용 성과는 경로 커버리지, 운영 결함률, 트랜잭션 분포 재현성으로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수):**
1. 최근 4주 APM·이벤트 로그에서 상위 사용자 경로를 추출하고 발생 확률과 업무 영향도를 곱해 테스트 우선순위를 산정함.
2. 부하 테스트는 실제 transaction mix를 반영해 조회 70%, 장바구니 20%, 결제 10%처럼 구성하고 오차 5%p 이하를 목표로 함.
3. 결제·인증·개인정보 기능은 사용 빈도와 무관하게 고위험 필수 케이스로 지정하고 릴리스 게이트에 포함함.

**결론 (2줄):**
- 기술사 판단: 사용자 행동 로그가 확보되고 운영 신뢰도가 목표인 서비스는 운영 프로파일 기반 테스트, 초기 개발 단계는 위험 기반 테스트를 병행함.
- 향후 방향: 운영 프로파일은 SLO, AIOps 이상 탐지, 자동 테스트 케이스 생성과 결합해 지속 테스트 체계로 확장됨.
