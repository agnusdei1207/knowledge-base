## Ⅰ. 개요
- 정의: 테스트 수행에 필요한 데이터를 생성, 가공, 배포, 폐기하는 전 과정의 관리 활동
- 배경: 개인정보보호 강화(GDPR, 가명정보 등) 및 테스트 결과의 신뢰성 확보 필요
- 출제 의도: 데이터 익명화 기법 및 TDM 프로세스의 효율적 운영 방안 이해

## Ⅱ. 구성요소
- 구조도
  [Prod DB] --(Subset/Masking)--> [Test Data Repo]
                                       |
    [Generator] -> [Validation] -> [Provisioning]

- 구성요소 표
| 관리 기법 | 설명 | 비유 |
| :--- | :--- | :--- |
| 데이터 마스킹 | 민감 정보를 별표(*) 등으로 치환 | 마스크 착용 |
| 서브세팅 | 운영 데이터 중 일부만 샘플링 추출 | 시식용 조각 |
| 가상 데이터 생성 | 실제 데이터 없이 규칙 기반으로 생성 | 가상 인물 설정 |
> 요약: 규제를 준수하면서도 실제 운영 환경과 유사한 고품질 데이터 공급

## Ⅲ. 절차
- 흐름도
  데이터 요건 분석 -> 추출 및 변환 -> 가명/익명화 -> 테스트 배포
- 4단계 설명
1. 데이터 요건 분석: 테스트 시나리오별 필요한 데이터 항목 및 규모 파악
2. 추출 및 변환: 운영 DB에서 조건에 맞는 데이터를 안전하게 추출 및 포맷팅
3. 가명/익명화: 개인 식별 정보를 암호화하거나 무작위 값으로 치환하여 보안성 확보
4. 테스트 배포: 필요한 시점에 자동화된 파이프라인을 통해 테스트 환경에 데이터 적재
> 요약: 신속한 데이터 공급을 통해 테스트 리드타임 단축 및 보안 사고 방지

## Ⅳ. 문제점
- 테스트 수행 후 데이터 오염(Data Corruption) 발생 시 원복 절차의 복잡성
- 운영 데이터가 너무 대규모여서 테스트 환경 구축 시 저장 공간 및 비용 부담 가중

## Ⅴ. 개선방안
- 데이터 가상화 기술을 활용한 빠른 스냅샷 복구 및 자원 효율성 증대
- 자동화된 TDM 도구 도입으로 데이터 생성 및 갱신 프로세스 상시화

## Ⅵ. 전망
- 합성 데이터(Synthetic Data) 기술을 활용하여 개인정보 이슈가 없는 대규모 데이터 생성
- CSF: 데이터 보안 정책 준수와 테스트 가용성 사이의 적절한 균형 유지
