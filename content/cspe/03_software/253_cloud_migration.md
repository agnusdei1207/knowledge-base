## Ⅰ. 개요
- 정의: 기존 온프레미스 자산을 클라우드 환경으로 이전하기 위한 6가지 전략임
- 배경: 비즈니스 민첩성 확보 및 인프라 현대화를 위한 체계적 접근법 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 6R 유형 | Rehost, Replatform, Refactor 등 | 매우높음 |
| 선정 기준 | 비용, 기간, 난이도 | 높음 |

## Ⅱ. 구성요소 (6R 전략)
- ASCII 구조도
  [ 온프레미스 ] ---+--- [ Rehost ] (단순 이전)
                    +--- [ Replatform ] (최적화)
                    +--- [ Refactor ] (재설계)

- 구성요소 표
| 유형 | 설명 | 비유 |
|------|------|------|
| Rehosting | 수정 없이 그대로 옮김 (Lift-and-Shift) | 단순 이사 |
| Replatforming | OS나 DB 버전만 클라우드용으로 변경 | 가구 교체 후 이사 |
| Refactoring | 클라우드 네이티브로 아키텍처 전면 수정 | 재건축 |
| Repurchasing | 기존 솔루션을 SaaS로 대체함 | 구독 서비스 전환 |
| Retaining | 이전하지 않고 현재 상태 유지함 | 현 거주지 유지 |
| Retiring | 불필요한 시스템을 폐기함 | 짐 정리 |

> 요약: 시스템의 가치와 비용을 고려하여 최적의 경로를 선택하는 가이드임

## Ⅲ. 절차
- ASCII 흐름도
  [자산 실사] -> [Migration 유형 결정] -> [이전 수행] -> [최적화/운영]
   (Inventory)      (Decision Matrix)     (Execution)     (Cloud Native)

- 4단계 설명
1. 분석: 전체 IT 자산의 의존 관계와 클라우드 적합성을 정밀 실사함
2. 전략수립: 6R 기준에 따라 업무별 이전 우선순위와 방식을 확정함
3. 실행: 자동화 도구를 활용하여 데이터와 애플리케이션을 단계적 이전함
4. 최적화: 클라우드 환경 안착 후 모니터링을 통해 비용과 성능을 조정함

> 요약: 철저한 사전 분석을 바탕으로 리스크를 최소화하며 점진적으로 이전함

## Ⅳ. 문제점
- 단순 Rehosting 위주의 이전은 클라우드의 진정한 이점(확장성 등) 활용 못함
- 이전 과정에서 데이터 유실이나 서비스 중단 시간(Downtime) 관리의 어려움 있음

## Ⅴ. 개선방안
- (단기) 초기에는 Rehost로 신속히 이전 후, 점진적으로 Refactor를 수행함
- (중기) 클라우드 마이그레이션 자동화 도구를 적극 활용하여 인적 오류 최소화함
- (장기) 전사적 디지털 전환(DX) 관점에서 클라우드 네이티브 역량 내재화함

## Ⅵ. 전망
- 생성형 AI가 마이그레이션 코드를 자동 생성하고 검증하는 단계로 진입할 것임
- 산업 특화 클라우드(Industry Cloud)로의 특화된 마이그레이션 전략이 부각됨
