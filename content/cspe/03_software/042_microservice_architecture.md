## 미리 알고가기

- MSA는 비즈니스 기능을 작은 서비스 단위로 나누는 분산 아키텍처임
- Bounded context는 같은 용어와 규칙이 유효한 도메인 경계임
- Eventual consistency는 여러 저장소가 즉시 같지 않아도 일정 시간 안에 맞춰지는 상태임

## 작성 근거(검토용)

- MSA는 서비스 경계, 독립 배포, 데이터 소유권, 분산 운영 부담을 핵심 축으로 설명함
- 모놀리식과 MSA는 배포 단위, 확장 방식, 소유 구조, 운영 한계를 기준으로 비교함
- 실무 판단은 서비스 간 호출 수, 동시 배포 비율, 보상 처리 성공률, 데이터 불일치 건수로 구체화함

## Ⅰ. 개요

- **정의/개념**: MSA는 비즈니스 기능을 데이터 소유권과 독립 배포 책임을 가진 서비스로 분리하는 분산 소프트웨어 구조임
- **배경/필요성**: 기능별 변경·확장과 팀별 배포를 분리하기 위해 비즈니스 책임에 따른 서비스 경계가 필요함

## Ⅱ. 특징

- 서비스별 독립 배포와 선택적 확장이 가능함
- 서비스별 소유 팀이 코드·데이터·배포·운영 책임을 함께 담당함
- 네트워크 호출과 데이터 분산이 늘어 운영 복잡도와 장애 지점도 늘어남
- 경계를 잘못 자르면 서비스만 많고 결합은 강한 분산 모놀리스가 되기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 모놀리식 | MSA |
|:---|:---|:---|
| 배포 단위 | 애플리케이션 전체를 한 번에 배포함 | 서비스별로 필요한 부분만 따로 배포함 |
| 확장 방식 | 전체 시스템을 함께 늘리는 경우가 많음 | 부하가 집중되는 서비스만 선택적으로 늘릴 수 있음 |
| 책임 소유 | 코드·데이터·운영 책임을 공동 관리 | 서비스별 팀이 코드·데이터·운영 책임 보유 |
| 운영 한계 | 작은 변경도 전체 릴리스와 충돌하기 쉬움 | 분산 데이터와 관측과 장애 분석 비용이 커짐 |

> 요약: 모놀리식은 하나의 배포·운영 단위, MSA는 서비스별 배포·데이터·운영 책임을 가짐.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 서비스 경계 | 도메인 기능별로 독립 배포와 책임 소유 단위를 정함 |
| API 계약 | 서비스 간 요청·응답 규약으로 변경 영향 범위를 통제함 |
| 데이터 소유권 | 서비스별 저장소 쓰기 권한을 분리하고 서비스 간 정합성 방식을 정함 |
| 관측·운영 계층 | 로그·추적·배포 자동화로 분산 호출과 장애 위치를 식별함 |

> 요약: 서비스 경계가 배포·데이터 소유 단위를 정하고 API 계약과 관측 계층이 분산 의존성을 통제함.

## Ⅵ. 실무 사례

1. 전자상거래 플랫폼은 바운디드 컨텍스트로 서비스를 분리하고 서비스 간 호출 수·동시 배포 비율을 확인함
2. 정산 서비스는 저장소를 분리하고 Saga 보상 절차를 적용해 보상 성공률·데이터 불일치 건수를 확인함

## Ⅶ. 결론

MSA는 바운디드 컨텍스트로 서비스와 데이터 소유권을 나누고 독립 배포·관측 체계를 함께 설계해야 함.
