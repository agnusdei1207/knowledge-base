## 미리 알고가기

- 예약 인스턴스는 일정 기간의 인스턴스 사용을 약정해 일치하는 사용량에 할인 요율을 적용함
- EC2 기준 리전 예약은 요율 혜택이며 가용 영역 예약은 용량 예약을 포함함
- 스팟 인스턴스는 공급자의 미사용 용량을 할인 요율로 사용하되 용량 회수로 중단될 수 있음
- 예약 적용률은 전체 대상 사용량 중 예약 요율이 적용된 비율임
- 예약 사용률은 구매한 예약 범위 중 실제 사용량이 차지한 비율임
- 체크포인트는 작업 진행 상태를 외부 저장소에 기록해 다른 인스턴스에서 이어서 처리하게 함
- 온디맨드는 장기 약정 없이 실행한 컴퓨팅 사용량에 기본 요율을 적용하는 방식임

## 작성 근거(검토용)

- 두 과금 방식은 할인율보다 사용 약정과 중단 가능성이 선택을 가르므로 이를 핵심 축으로 둠
- 과금 기반·약정·중단·용량·적합 업무·운영 조치를 비교하고 혼합 구성과 중단 절차로 연결함
- 제목부터 결론까지 5회 전수 검수하여 예약 요율과 용량 보장을 혼동하지 않도록 교정함

## Ⅰ. 개요

- **정의/개념**: 예약·스팟 인스턴스는 장기 사용 약정이나 미사용 공급 용량을 조건으로 컴퓨팅 요율을 낮추는 구매 방식임
- **배경/필요성**: 기준 부하와 중단 가능한 변동 부하의 비용을 줄이기 위해 사용 지속성·약정·복구 기준이 필요함

## Ⅱ. 특징

- 예약 인스턴스는 사용 여부와 별개로 약정 비용이 발생하므로 수요 예측이 필요함
- 스팟 인스턴스는 공급 용량 회수에 대비해 작업 분할·체크포인트·재시도가 필요함
- 기준 부하는 예약, 변동·배치 부하는 스팟으로 구성해 비용과 중단 영향을 분리할 수 있음
- 예약 적용률·사용률과 스팟 중단률·복구 시간을 서로 다른 지표로 관리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 예약 인스턴스 | 스팟 인스턴스 |
|:---|:---|:---|
| 과금 기반 | 약정 조건과 일치하는 사용량에 할인 요율 적용 | 공급자의 미사용 용량에 변동 요율 적용 |
| 사용 약정 | 계약 기간의 비용 지불 의무 존재 | 장기 사용 약정 없음 |
| 실행 지속성 | 과금 옵션 때문에 인스턴스를 회수하지 않음 | 용량 회수 시 인스턴스 중단 가능 |
| 용량 보장 | 리전 예약은 요율 혜택, 가용 영역 예약은 용량 예약 포함 | 요청 시 용량 확보를 보장하지 않음 |
| 적합 업무 | 사용량이 예측되는 상시 서버 | 재시도 가능한 배치·분산 작업 |
| 운영 조치 | 적용률·사용률과 만료 시점을 관리 | 중단 알림·체크포인트·대체 용량을 관리 |

> 요약: 예측 가능한 기준 부하는 예약, 중단 후 재개 가능한 작업은 스팟에 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 수요 기준선 | 시간대별 최소 인스턴스 수와 변동 폭을 계산함 |
| 예약 포트폴리오 | 인스턴스 속성·기간·결제 조건별 약정량을 관리함 |
| 스팟 풀 | 여러 인스턴스 유형·가용 영역에서 대체 용량을 요청함 |
| 작업 큐 | 작업을 재시도 가능한 단위로 나누어 실행 노드에 배분함 |
| 체크포인트 저장소 | 진행 상태와 중간 결과를 인스턴스 외부에 보존함 |
| 비용·중단 관측 | 예약 적용률·사용률과 스팟 중단·복구 시간을 수집함 |

```text
기준 부하 -> 예약 인스턴스
변동 작업 -> 작업 큐 -> 스팟 풀 -> 체크포인트
```

> 요약: 기준 부하는 예약 약정으로 처리하고 변동 작업은 체크포인트가 있는 스팟 풀에 배분함.

## Ⅴ. 스팟 중단 대응 흐름

```text
중단 신호 확인 -> 신규 작업 중지 -> 상태 저장·연결 해제 -> 대체 인스턴스 -> 작업 재개
```

1. **중단 신호 확인**: 인스턴스 메타데이터나 이벤트에서 회수 신호를 감지함
2. **신규 작업 중지**: 작업 큐가 해당 인스턴스에 새 작업을 배정하지 않음
3. **상태 저장·연결 해제**: 진행 상태를 저장하고 로드밸런서 대상에서 제거함
4. **대체 인스턴스 시작**: 다른 유형·가용 영역이나 온디맨드 용량을 요청함
5. **작업 재개**: 저장한 지점부터 작업을 실행하고 중복 결과를 검증함

> 요약: 스팟 중단 신호가 작업 배정 중지와 상태 저장을 거쳐 대체 인스턴스의 재개로 이어짐.

## Ⅵ. 실무 사례

1. 상시 API 서버는 예약 약정을 적용하고 예약 적용률·미사용 약정 비용을 확인함
2. 렌더링 작업은 스팟에서 체크포인트를 저장하고 중단률·작업 재개시간을 확인함

## Ⅶ. 결론

- 예약·스팟 인스턴스는 수요 예측 가능성과 중단 후 복구 가능성을 기준으로 조합해야 함
