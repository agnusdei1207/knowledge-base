# 📖 【암기용】 개념 완전 이해

## 한눈에
- **요구 페이징 (Demand Paging)**: 프로그램 실행 중 특정 페이지가 **실제로 필요할 때만** 메모리에 로드하는 방식. (필요할 때 호출)
- **프리페이징 (Prepaging)**: 페이지 폴트 발생 시, 당장 필요한 페이지 외에도 **가까운 미래에 쓰일 것으로 예상되는 페이지**를 미리 메모리에 올리는 방식. (미리 가져오기)
- **핵심 직관**: 공부할 때, 모르는 단어가 나올 때마다 사전을 찾는 것(요구 페이징) vs 오늘 공부할 범위의 단어들을 미리 다 찾아두는 것(프리페이징).

## 깊이 이해
- **Demand Paging의 경제성**: 프로그램의 90%는 거의 안 쓰임(예외 처리 코드 등). 필요한 10%만 메모리에 올리니 RAM을 획기적으로 아낄 수 있음.
- **Pure Demand Paging**: 프로그램 시작 시 아무것도 안 올리고 시작함. 첫 명령어부터 페이지 폴트가 터지며 하나씩 가져옴. 초반에 엄청 느림.
- **Prepaging의 도박**: 예상해서 미리 가져왔는데 안 쓰면 메모리 낭비 + 디스크 I/O 낭비. 하지만 순차적인 데이터 처리(배열 탐색 등)에서는 성능을 비약적으로 높임.
- **Valid-Invalid Bit**: 페이지 테이블에 있는 비트. 0(Invalid)이면 메모리에 없다는 뜻으로, 접근 시 CPU가 페이지 폴트 트랩을 발생시킴.

## 연결 개념
- **Virtual Memory (015)**: 요구 페이징을 통해 구현됨.
- **Page Fault (018)**: 요구 페이징의 핵심 트리거.
- **Locality (018)**: 프리페이징이 유효한 이유 (근처 페이지를 곧 쓸 확률이 높음).

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 요구 페이징은 **자원 효율성** 극대화를 위해 지연 로딩(Lazy Loading)을 수행하며, 프리페이징은 **응답 성능** 향상을 위해 선행 로딩(Pre-loading)을 수행함.
> 2. **기술적 핵심**: **Valid-Invalid Bit**를 이용한 하드웨어 트랩 메커니즘을 기반으로 하며, 지역성(Locality) 원리를 활용하여 페이지 부재 오버헤드를 제어함.
> 3. **판단**: 메모리가 부족하면 요구 페이징을 고수하고, 대규모 데이터 처리나 프로그램 초기 구동 속도가 중요하면 프리페이징을 혼용함.

## Ⅰ. 효율적 페이지 로딩 전략, 요구 페이징과 프리페이징 개요

- **Demand Paging**: 실행 과정에서 참조되는 페이지가 메모리에 없을 때만 I/O를 발생시켜 적재하는 지연 전략.
- **Prepaging**: 페이지 폴트 횟수를 줄이기 위해 과도하게 참조될 가능성이 높은 페이지를 미리 적재하는 예측 전략.

## Ⅱ. 요구 페이징(Demand Paging)의 메커니즘

### 1. 동작 절차 (Step-by-Step)
1. **Reference**: CPU가 특정 주소 참조.
2. **Trap**: 페이지 테이블의 Invalid 비트 확인 후 **Page Fault** 발생.
3. **OS Intervention**: 보조기억장치에서 해당 페이지 탐색.
4. **I/O**: 빈 프레임에 페이지 로드.
5. **Update**: 페이지 테이블을 Valid로 갱신.
6. **Restart**: 중단된 명령어 재시행.

### 2. 장점 및 단점
- **장점**: 메모리 절약, 프로세스 생성 속도 향상, 다중 프로그래밍 정도(MPD) 증가.
- **단점**: 잦은 페이지 폴트로 인한 초기 구동 지연, I/O 오버헤드.

## Ⅲ. 프리페이징(Prepaging)의 원리 및 효용성

### 1. 배경: 지역성 (Locality)
- 프로세스가 페이지 $N$을 참조했다면, 잠시 후 $N+1, N+2$를 참조할 확률이 매우 높다는 원리를 이용함.

### 2. 특징 분석
- **성능**: 페이지 폴트 발생 빈도를 낮추어 연속적인 처리 속도 향상.
- **리스크**: **잘못된 예측(Bad Guess)** 시 메모리 낭비 및 디스크 대역폭 소모.
- **적용**: 대규모 배열 처리, 비디오 스트리밍, 프로그램 시작 시 핵심 모듈 로딩.

## Ⅳ. 요구 페이징 vs 프리페이징 비교

| 비교 항목 | 요구 페이징 (Demand Paging) | 프리페이징 (Prepaging) |
|:---:|:---|:---|
| **로드 시점** | 실제 참조 시 (On-demand) | 참조 전 예상 시 (In-advance) |
| **메모리 활용** | 극도로 효율적 | 일부 낭비 가능성 존재 |
| **응답 속도** | 초기 지연 발생 (Cold Start) | 초기 구동 및 연속 처리 속도 빠름 |
| **I/O 부하** | 산발적 발생 | 일시적 집중 발생 |
| **성패 결정** | - | **예측 정확도**에 따라 달라짐 |

## Ⅴ. 기술적 심화: 쓰기 시 복사 (Copy-on-Write, CoW)
- **개념**: `fork()`로 프로세스 생성 시, 부모의 페이지를 즉시 복사하지 않고 요구 페이징처럼 공유하다가, **쓰기(Write)** 작업이 발생할 때만 해당 페이지를 복사하는 최적화 기법.
- **가치**: 요구 페이징의 철학을 프로세스 생성에 적용하여 메모리와 시간을 획기적으로 절약.

## Ⅵ. 기술사 관점의 결론 및 제언
- 요구 페이징은 가상 메모리의 근간이며, 프리페이징은 이를 보완하는 가속기임.
- **실무 제언**: 현대 OS는 순수한 요구 페이징보다, 페이지 폴트 발생 시 인접 페이지 수 개를 한꺼번에 읽어오는 **Page Clustering**이나 **Read-ahead** 기법을 통해 프리페이징 효과를 기본적으로 취하고 있음. 시스템 튜닝 시 스토리지 성능에 따라 이 클러스터 크기를 최적화하는 접근이 필요함.
