## Ⅰ. 개요
- 정의: 아키텍처 원칙과 표준이 실제 개발 전 과정에서 준수되도록 관리·감독하는 체계임
- 배경: 아키텍처 침식(Erosion) 방지 및 전사적 기술 일관성 유지를 통한 자산 가치 보호
- 출제 의도: 기술 표준 수립, 준수 여부 점검(Compliance), 예외 관리 프로세스 이해도 확인

## Ⅱ. 구성요소
- ASCII 구조도
  [Governance Board] -> [Standards/Policy] -> [Project Teams]
          ^                      |                   |
          +-------(Audit)--------+-------(Follow)----+
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 아키텍처 원칙 | 기술적 의사결정의 근거가 되는 기본 지침 | 헌법/법령 |
| 준수 평가(Audit) | 설계/구현이 표준을 따르는지 주기적 검증 | 정기 검사 |
| 예외 관리 | 표준 미준수 사유 승인 및 기술 부채 기록 | 특별 허가 |
> 요약: 원칙을 세우고 이를 준수하는지 감시하며 예외 상황을 체계적으로 관리함

## Ⅲ. 절차
- ASCII 흐름도
  Policy Set -> Review/Support -> Compliance Check -> Action
- 4단계 설명
1. Policy Set: 전사 공통 기술 스택 및 아키텍처 설계 원칙 확립함
2. Review/Support: 프로젝트 초기 아키텍처 검토 및 가이드 제공함
3. Compliance Check: 정적 분석, 코드 리뷰 등으로 표준 준수 여부 점검함
4. Action: 위반 사항에 대한 시정 요구 또는 기술 부채(Tech Debt) 등록함
> 요약: 정책 수립 후 지속적 지원과 점검을 통해 아키텍처 무결성을 유지함

## Ⅳ. 문제점
- 모든 기술 결정을 위원회 승인 대상으로 두면 검토 대기 시간이 늘고 프로젝트별 제약 반영이 지연됨

## Ⅴ. 개선방안
- 공통 규칙은 자동 검사하고 고위험 예외만 위원회가 검토하도록 승인 범위와 처리 기한을 정의함

## Ⅵ. 전망
- 클라우드 가드레일(Guardrails) 기반의 실시간 정책 위반 자동 탐지 및 교정
- CSF: 거버넌스가 규제가 아닌 '도움'이 된다는 인식 확산과 아키텍처 위원회의 전문성 확보임
