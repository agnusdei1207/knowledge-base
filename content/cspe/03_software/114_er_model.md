## Ⅰ. 개요
- **정의**: 엔티티, 속성, 관계로 현실 세계의 데이터 구조를 표현하는 개념적 데이터 모델임
- **배경/필요성**: 개념 설계 없이 바로 테이블을 만들면 업무 의미가 누락되고 구조 변경이 빈번함
- **비유**: 사물(엔티티)과 사물 간의 인연(관계)을 지도로 그린 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개념 모델링 도구 이해 | 엔티티·속성·관계·카디널리티 구분 | 약한 엔티티와 식별 관계 언급 |

> 요약: 엔티티-속성-관계 3요소로 업무 데이터를 시각화하는 개념 모델임

## Ⅱ. 구성요소
```text
ER Model
 +-- Entity --------- 독립적 관리 대상(사각형)
 +-- Attribute ------- 엔티티의 특성(타원)
 +-- Relationship ---- 엔티티 간 연관(마름모)
 +-- Cardinality ----- 1:1, 1:N, M:N 대응 수
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Entity | 업무상 독립 식별·관리되는 데이터 객체 | 명사(고객, 주문) |
| Attribute | 엔티티를 설명하는 개별 속성(PK, FK 포함) | 사람의 이름·나이 |
| Relationship | 엔티티 간 업무적 연관과 참여 조건 | 동사(구매하다) |

> 요약: 엔티티·속성·관계·카디널리티가 ER 모델의 4대 구성 요소임

## Ⅲ. 절차
```text
엔티티 도출 --> 속성 정의 --> 관계 설정 --> ERD 검증
```
- 1단계: 업무 분석 결과에서 핵심 엔티티 식별
- 2단계: 각 엔티티의 속성과 PK(기본키) 정의
- 3단계: 엔티티 간 관계 유형(1:1, 1:N, M:N)과 참여 조건(전체/부분) 설정
- 4단계: ERD를 현업과 검증하여 누락 엔티티·관계 보완

> 요약: 도출-정의-설정-검증 4단계로 ERD를 완성함

## Ⅳ. 문제점
- 엔티티 과다 분할: 불필요한 세분화로 관계가 복잡해지고 가독성 저하
- M:N 관계 미해소: 논리 모델 전환 시 교차 엔티티 누락으로 구현 오류 발생
- 카디널리티 오류: 업무 규칙과 맞지 않는 대응 수 설정 시 데이터 정합성 훼손

> 요약: 과다 분할, M:N 미해소, 카디널리티 오류가 ER 모델링 주요 결함임

## Ⅴ. 개선방안
1. 단기: 엔티티 통합 기준(식별자 동일성)을 수립하여 과다 분할 방지
2. 중기: M:N 관계를 교차 엔티티로 변환하는 체크리스트 적용
3. 장기: 업무 규칙 기반 카디널리티 자동 검증 도구 도입

> 요약: 통합 기준, 교차 엔티티 변환, 자동 검증으로 모델 정확도를 높임

## Ⅵ. 전망
- 발전 방향: 확장 ER(EER) 모델이 상속·집합 표현까지 지원하며 활용 확대
- 기술사적 판단: 관계형 DB 설계의 출발점으로 여전히 표준 방법론임
- 기술사 제언: ERD 작성 후 논리 모델(정규화 115 참조)로의 체계적 전환 필요
