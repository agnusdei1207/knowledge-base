## 미리 알고가기

- Bronze는 원천 데이터를 재처리할 수 있도록 수집 형태와 이력을 보존하는 계층임
- Silver는 형식·중복·키·품질 규칙을 적용해 표준화한 상세 데이터 계층임
- Gold는 특정 분석·응용 목적에 맞춘 집계·차원·서빙 데이터 계층임
- 품질 게이트는 상위 계층으로 게시하기 전에 스키마·완전성·참조 규칙을 판정함
- 격리 영역(Quarantine)은 품질 규칙을 통과하지 못한 레코드와 판정 사유를 보존함
- 재처리는 Bronze의 원천 이력에서 새 규칙으로 Silver·Gold를 다시 생성하는 작업임

## 작성 근거(검토용)

- 메달리온은 Bronze·Silver·Gold별 데이터 상태·품질·소비 목적과 재처리 경계를 핵심으로 선정함
- 비교표는 세 계층의 데이터 상태·품질 기준·변경 원칙을 같은 질문으로 대비함
- 절차는 원천 보존부터 품질 판정과 목적별 게시까지 데이터 상태가 실제로 변하는 순서를 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 계층별 역할 중복을 제거함

## Ⅰ. 개요

- **정의/개념**: 메달리온 아키텍처는 데이터를 Bronze·Silver·Gold로 나눠 원천 보존·표준화·품질 검증·목적별 제공을 수행하는 설계 패턴임
- **배경/필요성**: 원천 재처리 가능성을 유지하면서 분석 사용자가 품질이 확인된 데이터를 소비하도록 상태와 게시 기준이 분리된 계층이 필요함

## Ⅱ. 특징

- Bronze가 수집 시각·원천 위치와 함께 원본을 보존해 정제 규칙 변경 시 재처리 기준을 제공함
- Silver가 스키마·키·중복·참조 규칙을 적용해 여러 원천을 공통 상세 모델로 통합함
- Gold는 보고서·API·모델 학습에 맞춘 소비 목적별 집계와 서빙 구조를 제공함
- 계층 간 품질 게이트와 격리 영역이 실패 레코드의 전파 범위를 제한함
- 계층별 테이블 수명주기와 재생성 원칙을 정하지 않으면 데이터 복제와 저장 비용이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | Bronze | Silver | Gold |
|:---|:---|:---|:---|
| 데이터 상태 | 원천 형식과 수집 이력을 최소 변환으로 보존 | 형식 통일·중복 제거·키 매핑을 거친 표준 상세 데이터 | 집계·차원 모델·업무 지표로 가공한 소비 목적별 데이터 |
| 품질 기준 | 수집 성공·스키마 식별 | 완전성·유효성·참조·중복 규칙 | 지표 정의·원천 대사·최신성 |
| 변경 원칙 | 원천 이력 유지·추가 저장 | 규칙 변경 시 Bronze에서 재생성 | 소비 요구 변경 시 Silver에서 재생성 |

> 요약: Bronze는 원천을 보존하고 Silver는 품질 규칙으로 표준화하며 Gold는 목적별 지표를 생성하되, 규칙·요구 변경 시 하위 계층에서 재생성함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 수집·Bronze | 원천 데이터와 수집 시각·위치·스키마 정보를 변경 없이 저장함 |
| 품질 규칙·격리 | 레코드를 검사하고 위반 데이터와 판정 사유를 별도 보존함 |
| 표준화·Silver | 코드·타입·키·중복을 정리해 공통 상세 모델을 생성함 |
| 집계·Gold | 소비 목적별 사실·차원·집계·모델 학습용 특성 데이터를 생성함 |
| 카탈로그·계보 | 계층별 스키마·소유자·품질 결과와 변환 경로를 연결함 |
| 오케스트레이터 | 계층 의존성·재시도·재처리와 데이터 구간별 실행을 조정함 |

```text
원천 -> Bronze -> Silver -> Gold -> 업무 분석·API·모델
          |          |
       재처리      품질 게이트·격리
```

> 요약: 카탈로그와 품질 게이트가 Bronze 원천, Silver 표준 데이터, Gold 소비 데이터를 하나의 계보로 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
Bronze 원천·버전 보존 -> Silver 품질·표준화 -> Gold 집계 -> 소비 게시
```

1. **원천 보존**: 배치·스트림 입력과 수집 메타데이터를 파티션·버전별로 Bronze에 저장함
2. **표준화**: 품질 규칙을 판정하고 통과 데이터의 타입·코드·키를 Silver에 통합함
3. **목적별 집계**: Silver 상세 데이터에서 업무 지표·차원·모델 학습용 특성을 Gold로 생성함
4. **소비 게시**: 카탈로그·계보·품질 결과와 함께 업무 분석·API·모델에 공개함

> 요약: 원천을 Bronze에 보존하고 품질을 통과한 Silver 상세 데이터로 Gold 소비 모델을 생성함.

## Ⅵ. 실무 사례

1. 응용 로그 분석은 Bronze 원본과 Silver 표준 이벤트를 분리하고 격리 건수·Silver 처리 지연을 확인함
2. 주문 매출 분석은 Silver 주문을 Gold 일별 매출로 집계하고 원천 대사 차이·데이터 최신성을 확인함

## Ⅶ. 결론

- 메달리온은 계층별 데이터 상태·품질 게이트·재처리 원천·소비 목적과 복제 비용을 기준으로 설계해야 함
