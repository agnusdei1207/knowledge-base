## 핵심 인사이트 (3줄 요약)
- 늪(Swamp)으로 변해버린 데이터 레이크를 구원하기 위해, 데이터를 원시(Bronze) ➡️ 정제(Silver) ➡️ 통계(Gold)의 **3단계 계층으로 분리하여 데이터의 품질을 점진적으로 끌어올리는 레이크하우스 표준 파이프라인 설계 패턴**.
- Databricks가 제창한 개념으로, 각 단계를 거칠 때마다 데이터는 깨끗해지고(정합성 확보), 스키마가 엄격해지며, 쿼리 속도가 극대화되도록 구조화됨.
- "모든 부서가 Gold 계층의 믿을 수 있는 단일 진실 공급원(SSOT)만 보고 의사결정을 내린다"는 거버넌스(Governance) 확립이 이 아키텍처의 최종 목적임.

## Ⅰ. 개요 및 필요성
- **개요**: 데이터 레이크하우스 환경에서 데이터의 품질과 구조를 Bronze, Silver, Gold 계층으로 논리적으로 분리하여 관리하는 데이터 엔지니어링 디자인 패턴.
- **필요성**: 데이터 레이크(S3)에 데이터를 마구잡이로 쌓아두었더니, 신입 분석가가 쓰레기 값(Null, 중복 데이터)이 섞인 로그 원본을 그대로 읽고 "올해 매출 100배 상승!"이라는 엉터리 보고서를 경영진에게 올리는 대참사가 발생함. "데이터를 방치하지 말고, 정수기 필터처럼 단계를 거칠수록 깨끗해지는 엄격한 품질 관리 체계를 만들자!"는 목적으로 도입됨.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **1. Bronze 계층 (Raw Data / 흙탕물)**:
  - 수집된 원본 데이터(JSON, CSV, 이미지, DB CDC)를 **아무런 가공 없이 있는 그대로(as-is)** 영구 보존하는 구역.
  - "나중에 파이프라인에 버그가 생기면 언제든 처음부터 다시 계산할 수 있어야 한다"는 원칙하에, Append-only(추가만 함)로 관리됨. (스키마 없음).
- **2. Silver 계층 (Filtered & Cleansed / 정수된 물)**:
  - Bronze 데이터를 읽어서 중복을 제거하고, 널(Null) 값을 처리하며, 날짜 형식을 'YYYY-MM-DD'로 예쁘게 통일한 **정제된 마스터 데이터(Enterprise View)** 구역.
  - 데이터 사이언티스트가 AI 머신러닝 모델을 학습시킬 때 가장 많이 가져다 쓰는 거대한 고품질 테이블들의 집합임. (스키마 엄격히 적용).
- **3. Gold 계층 (Business Level / 얼음과 음료수)**:
  - 경영진과 비즈니스 분석가(BI 툴)가 당장 화면에서 볼 수 있게, Silver 데이터를 가져다가 부서별 목적에 맞게 조인(JOIN)하고 집계(SUM, AVG)해 놓은 최종 요약 테이블(Data Mart 역할).
  - "일별 부서별 총매출 테이블" 같이 철저하게 비즈니스 요구사항에 맞춰 최적화(비정규화)되어 있어 쿼리가 0.1초 만에 날아감.

```text
[ 메달리온 아키텍처의 데이터 흐름도 (정수기 필터 비유) ]

 🚰 외부 데이터 소스 (Kafka, MySQL, App Log)
        ⬇️
 🥉 [ Bronze (저수지) ] ➡️ "쓰레기가 섞여 있어도 일단 다 받아! (History 100% 보존)"
        ⬇️ (정제, 필터링, 정규화 연산)
 🥈 [ Silver (정수 탱크) ] ➡️ "오타 수정 완료! 깨끗하고 신뢰할 수 있는 전사 공통 데이터 완성!" 
        ⬇️ (조인, 통계 집계 연산)
 🥇 [ Gold (생수병) ] ➡️ "부서별 맞춤형(마케팅용, 재무용) 최종 통계 테이블 완성! 경영진 보고 올려!"
```

## Ⅲ. 비교 및 연결
| 구분 | Bronze Layer (Raw) | Silver Layer (Cleansed) | Gold Layer (Aggregated) |
|---|---|---|---|
| **주요 작업** | 수집, 압축, 파티셔닝 | **정제, 필터링, 타입 변환** | **비즈니스 로직, 조인, 집계** |
| **데이터 형태** | JSON, 원본 로그 덤프 | **정규화된 RDB 형태 테이블** | **비정규화된 통계/뷰 테이블** |
| **주 사용층** | 데이터 엔지니어 | **데이터 사이언티스트 (AI/ML)** | **비즈니스 애널리스트 (BI)** |
| **DW 역할 매핑**| ODS (Operational Data Store) | **EDW (Enterprise DW)** | **Data Mart (부서별 마트)** |

## Ⅳ. 실무 적용 및 기술사 판단
- **오픈 테이블 포맷(Delta/Iceberg)의 필수 적용**: 메달리온 아키텍처가 실제로 굴러가려면, Bronze ➡️ Silver로 넘어갈 때 원본 데이터가 변경/삭제(CDC)된 내역을 트랜잭션으로 안전하게 반영(UPSERT)할 수 있어야 함. 따라서 실무 아키텍트는 깡통 Parquet 파일만 쓰면 안 되고, 반드시 Delta Lake나 Apache Iceberg 같은 테이블 포맷을 도입하여 파이프라인의 ACID 안정성을 담보해야 함.
- **파이프라인의 멱등성(Idempotency) 확보**: Silver 연산을 하다가 서버가 뻗어서 재시작했을 때, 데이터가 2배로 뻥튀기되면 큰일 남. 기술사는 파이프라인(Airflow + Spark)을 설계할 때 "어제 날짜 배치 작업을 100번 다시 돌려도, Silver와 Gold 테이블의 결과는 1번 돌렸을 때와 100% 동일하다(Overwrite or Merge)"는 멱등성 원칙을 최우선 설계 기준으로 삼아야 함.
---
## Ⅴ. 기대효과 및 결론
- 거대한 데이터 레이크 안에서 데이터가 어떤 상태인지(쓰레기인지, 금괴인지)를 직관적으로 분류하여, 데이터 소비자(조직원)가 의심 없이 데이터를 믿고 쓸 수 있는 거버넌스 체계를 확립함.
- 전통적인 DW 시대의 ETL (ODS ➡️ DW ➡️ DM) 개념을 클라우드 레이크하우스 시대의 분산 컴퓨팅(Spark, Iceberg) 환경에 맞게 가장 우아하고 현대적으로 재해석한 파이프라인의 글로벌 표준임.

### 👶 어린이를 위한 3줄 비유 설명
1. **브론즈(동메달)** 구역은 농장에서 갓 따온 흙 묻은 감자를 껍질도 안 까고 박스째로 다 쌓아둔 창고예요.
2. **실버(은메달)** 구역은 감자를 물로 깨끗이 씻고, 썩은 건 버리고, 예쁘게 깎아서 요리하기 직전 상태로 준비해 둔 냉장고예요.
3. **골드(금메달)** 구역은 깎은 감자를 튀겨서 맛있는 '감자튀김(통계)'으로 완벽하게 요리해 놓은 식탁이에요. 사장님(경영진)은 식탁에 있는 감자튀김만 바로 집어 먹으면 된답니다!
