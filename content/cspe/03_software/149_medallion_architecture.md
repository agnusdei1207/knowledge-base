# 📖 【암기용】 개념 완전 이해

> 목적: 메달리온 아키텍처를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 메달리온 아키텍처는 **데이터 레이크하우스**에 쌓이는 데이터를 **Bronze(원본) → Silver(정제) → Gold(집계)** 3계층으로 단계적으로 승격시켜 **데이터 품질**을 관리하는 설계 패턴이다.
- **왜 필요한가**: 원천 데이터를 그대로 분석에 쓰면 사용자마다 다른 방식으로 중복 제거·결측 처리를 하게 되어 같은 지표(예: 매출)가 팀마다 다르게 계산되는 KPI 불일치가 생긴다. 계층을 나누면 "정제는 어디서, 지표 계산은 어디서" 책임이 명확해진다.
- **핵심 직관**: 원석(Bronze)을 원형 그대로 보관하고, 불순물을 제거한 소재(Silver)를 만든 뒤, 완제품 보석(Gold)으로 가공하는 3단 공정이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 데이터 레이크하우스 | 메달리온 아키텍처가 얹히는 상위 플랫폼 | 계층 구조를 담는 그릇 |
| 데이터 품질(Data Quality) | 완전성·정확성·일관성 등을 지표로 관리하는 것 — 메달리온이 단계적으로 끌어올리려는 대상 | 원석에서 가공품으로 올라가는 품질 등급 |
| Bronze 계층 | 원천 데이터를 가공 없이 그대로 append하는 계층(schema drift까지 포함해 원본 보존) | 창고에 원자재를 있는 그대로 쌓아둠 |
| Silver 계층 | 중복 제거·결측 처리·코드 표준화·조인 등으로 정규화한 계층 | 세척·분류를 마친 재료 |
| Gold 계층 | 도메인 KPI·집계·BI/ML 소비용 데이터 마트 | 손님상에 나가는 완성 요리 |
| 데이터 늪(Data Swamp) | 승격 기준 없이 무분별하게 쌓여 아무도 신뢰하지 못하는 레이크 — 메달리온이 막으려는 실패 상태 | 정리 안 된 창고에서 물건을 못 찾음 |
| 스키마 드리프트(Schema Drift) | 원천 시스템 스키마가 예고 없이 바뀌는 현상 | 납품업체가 말없이 규격을 바꿈 |
| 멱등성(Idempotency) | 같은 배치를 다시 실행해도 결과가 같아지는 성질 — 재처리(backfill) 안전성의 핵심 | 리셋 버튼을 눌러도 항상 같은 결과 |

## 깊이 이해

### 왜 필요했나 — 레이크가 '늪'이 되는 이유 (배경)
- 데이터 레이크는 스키마 제약 없이 어떤 형식이든 받을 수 있다는 게 장점이지만, 승격 기준이 없으면 분석가 A는 한 방식으로 중복을 제거하고 분석가 B는 다른 방식으로 처리해 같은 "일일 매출"이 팀마다 다른 숫자로 나온다. 메달리온은 "정제는 Silver에서 한 번만, KPI 계산은 Gold에서 한 번만" 하도록 강제해 이 문제를 없앤다.

### Bronze — 왜 원본을 그대로, append로만 보존하나
- Bronze는 원본을 절대 수정하지 않고 append만 한다. 이유는 재처리(backfill)와 감사(audit) 때문이다 — 만약 Silver 정제 로직에 버그가 있었다는 게 나중에 발견되면, Bronze의 원본 이벤트가 그대로 남아 있어야 그 시점부터 정확하게 재처리할 수 있다.
- **예시**: 주문 시스템의 CDC(변경 데이터 캡처) 이벤트를 JSON 원형 그대로 Bronze에 append한다. 원천 컬럼이 갑자기 하나 추가돼도(schema drift) Bronze는 이를 그대로 받아들이고 거부하지 않는다.

### Silver — 구체적으로 무엇을 정제하나
- PK 중복 제거(예: 같은 order_id가 재전송으로 3번 들어오면 최신 1건만 남김), 결측치 처리, 코드 표준화(예: 성별 값이 원천마다 'M'/'Male'/1로 제각각인 것을 'MALE' 하나로 통일), 여러 원천 테이블 조인을 수행한다.
- **수치 예**: 원천 CDC 이벤트 1,000만 건 중 재전송 중복이 5%(50만 건) 섞여 있다면, Silver에서 PK 기준 중복 제거를 거쳐 유효 레코드 950만 건만 남긴다. 정제 로직이 Silver 한 곳에만 있으므로 이후 모든 소비자가 같은 950만 건을 본다.

### Gold — 집계와 도메인 마트
- Gold는 Silver의 정규화된 데이터를 도메인 관점(매출, 반품률, 재고회전율 등)으로 집계한 최종 소비 테이블이다. BI 대시보드, ML 피처, API가 여기서 직접 읽는다.
- **예시**: Silver의 정제된 주문·반품 테이블을 조인해 Gold에 `일별 매출`, `일별 반품률` 테이블을 만든다. 집계 로직(semantic layer)이 Gold 한 곳에만 있으므로 부서마다 "매출"의 정의가 달라지는 KPI mismatch를 막는다.

### 2계층이면 충분한 경우 vs 3계층이 필요한 경우 (판별원리)
- 소비 조직이 1~2개뿐이고 정제 로직이 단순하면 Raw+Mart 2계층으로도 충분하다.
- 소비 조직이 3개 이상이거나 같은 정제 로직을 여러 팀이 중복 구현하고 있거나, 감사·재처리 요구(예: 규제 데이터)가 있다면 Bronze/Silver 분리가 반드시 필요하다 — Silver를 공통 자산으로 재사용해 중복 정제를 없앨 수 있기 때문이다.

### 비유와 흔한 오해
- **비유**: 원석 보관(Bronze) → 세공(Silver) → 완제품 진열(Gold)의 보석 가공 3단계와 같다.
- **오해**: Bronze/Silver/Gold라는 이름만 붙이고 실제로는 계층별 품질 규칙·소유자(owner)·SLA·재처리 기준이 없으면 아무 효과가 없다. 색깔 이름은 계약이 아니라 결과다 — 승격 기준이 진짜 핵심이다.

## 연결 개념
- 데이터 레이크하우스: 메달리온 아키텍처가 적용되는 대표 플랫폼
- 오픈 테이블 포맷(Delta Lake 등): Bronze/Silver/Gold 테이블을 실제로 구현할 때 쓰는 저장 포맷
- 데이터 품질 관리: 계층 승격 기준(품질 규칙)을 정의하는 핵심 통제

## Ⅰ. 개요 및 필요성

- 개요: 메달리온 아키텍처는 데이터 품질 계층화 패턴이다.
- 배경: 원천 데이터를 Bronze에 보존하고 Silver에서 정제하며 Gold에서 업무 지표로 제공해야 품질 책임을 분리할 수 있다.
- 필요성: Bronze/Silver/Gold 계층으로 데이터 늪, 중복 정제, KPI 불일치를 방지한다.

## Ⅱ. 구조 및 구성요소

```text
Source -> Bronze Raw -> Silver Cleaned -> Gold Business Mart -> BI / ML / API
                  +-> Lineage / Quality Rule
                  +-> Backfill / SLA
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Bronze | 원천 원본 보존 | append, schema drift 기록 |
| Silver | 정제·표준화·중복 제거 | PK, 코드, 결측 처리 |
| Gold | KPI·집계·도메인 마트 | BI, ML feature, API |
| Governance | 품질·계보·권한 관리 | owner, SLA, audit |

> 요약: 메달리온 아키텍처는 원시, 정제, 업무 제공 계층을 분리해 품질과 책임을 단계적으로 관리한다.

## Ⅲ. 동작원리 및 흐름도

```text
원천 적재 -> Bronze 원본 저장 -> 품질 검사 -> Silver 정제
-> Gold 집계 / 모델링 -> 소비 서비스 제공 -> lineage / SLA 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Bronze에 원본 이벤트·파일 적재 | checksum, 적재 누락 0건 |
| 2 | Silver에서 중복·결측·코드 표준화 | 품질 규칙 통과율 99% |
| 3 | Gold에서 업무 KPI와 feature 생성 | 집계 오차 0.01% 이하 |
| 4 | BI/ML/API 제공 후 계보 추적 | SLA 준수율 99% |

> 요약: 메달리온은 계층 승격마다 품질 검사를 수행해 원시 데이터에서 업무 지표까지 신뢰 경로를 만든다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. Bronze는 원천 원본 30~90일 이상 보존, Silver는 PK 중복·결측·코드 표준화 규칙 20개 이상 적용
2. Gold는 도메인 KPI와 semantic layer를 연결하고 집계 오차 0.01% 이하 reconciliation을 일 단위 수행
3. 계층별 owner, SLA, lineage, backfill runbook을 등록해 장애 재처리 RTO 2시간 이하 목표 설정

**결론 (2줄):**
- 기술사 판단: 원시 데이터 보존과 공통 KPI 제공을 동시에 요구하면 메달리온, 단일 부서 단순 리포트는 2계층 구조도 가능
- 향후 방향: 메달리온은 데이터 제품, 데이터 메시, 레이크하우스 거버넌스와 결합해 도메인별 품질 책임 구조로 발전

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "메달리온 아키텍처를 설명하시오" | Bronze/Silver/Gold 승격 흐름 | 단일 레이크 대비 품질·재처리 차이 |
| 요구사항 명시형 | "설계하시오", "도입 방안", "문제점 대책" | 계층별 DQ rule, SLA, lineage 설계 | 데이터 늪 방지와 KPI 일관성 기준 |

> 요약: 설명형은 계층 목적, 설계형은 품질 승격 기준과 운영 SLA 중심으로 전환한다.
