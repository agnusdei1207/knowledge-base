# 📖 【암기용】 개념 완전 이해

> 목적: 메달리온 아키텍처를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 메달리온 아키텍처는 데이터 레이크하우스 데이터를 Bronze, Silver, Gold 계층으로 나누어 품질을 단계적으로 높이는 설계 패턴임
- **왜 필요한가**: 원천 데이터를 바로 분석에 쓰면 중복, 결측, 지표 불일치가 발생함. 계층을 나누면 원시 보존, 정제, 업무 지표 제공 역할이 명확해짐.
- **핵심 직관**: 원석을 보관하고, 불순물을 제거하고, 완제품 보석으로 가공하는 3단 공정임.

## 깊이 이해
- **배경·문제의식**: 데이터 레이크는 모든 데이터를 받을 수 있지만 품질 단계가 없으면 사용자마다 다른 정제 로직을 적용해 지표가 달라짐.
- **작동 원리**: Bronze는 원천 원본, Silver는 정제·표준화·중복 제거, Gold는 집계·도메인 KPI·BI 제공 테이블로 구성함.
- **비유**: 식재료 창고(Bronze), 손질된 재료(Silver), 완성 메뉴(Gold)를 분리해 주방 작업 품질을 관리하는 방식임.
- **구체 예시**: 주문 CDC를 Bronze에 append, Silver에서 PK 중복 제거와 고객 코드 표준화, Gold에서 일별 매출·반품률 KPI로 집계함.
- **흔한 오해·주의점**: 세 계층 이름만 붙이면 끝이 아님. 계층별 품질 규칙, 재처리 기준, 소유자, SLA가 있어야 함.

## 연결 개념
- 데이터 레이크하우스: 메달리온 아키텍처가 적용되는 대표 플랫폼
- Delta Lake: Bronze/Silver/Gold 테이블 구현에 자주 쓰이는 포맷
- 데이터 품질: 계층 승격 기준을 정의하는 핵심 통제

## Ⅰ. 개요 및 필요성

메달리온 아키텍처는 레이크하우스 데이터 품질 계층화 패턴이다. 원천 데이터를 Bronze에 보존하고, Silver에서 정제하며, Gold에서 업무 지표로 제공한다. 데이터 늪, 중복 정제, KPI 불일치를 방지하기 위해 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
Source -> Bronze Raw -> Silver Cleaned -> Gold Business Mart -> BI / ML / API
                  +-> Lineage / Quality Rule
                  +-> Backfill / SLA
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Bronze | 원천 원본 보존 | append, schema drift 기록 |
| Silver | 정제·표준화·중복 제거 | PK, 코드, 결측 처리 |
| Gold | KPI·집계·도메인 마트 | BI, ML feature, API |
| Governance | 품질·계보·권한 관리 | owner, SLA, audit |

> 요약: 메달리온 아키텍처는 원시, 정제, 업무 제공 계층을 분리해 품질과 책임을 단계적으로 관리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
원천 적재 -> Bronze 원본 저장 -> 품질 검사 -> Silver 정제
-> Gold 집계 / 모델링 -> 소비 서비스 제공 -> lineage / SLA 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Bronze에 원본 이벤트·파일 적재 | checksum, 적재 누락 0건 |
| 2 | Silver에서 중복·결측·코드 표준화 | 품질 규칙 통과율 99% |
| 3 | Gold에서 업무 KPI와 feature 생성 | 집계 오차 0.01% 이하 |
| 4 | BI/ML/API 제공 후 계보 추적 | SLA 준수율 99% |

> 요약: 메달리온은 계층 승격마다 품질 검사를 수행해 원시 데이터에서 업무 지표까지 신뢰 경로를 만든다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. Bronze는 원천 원본 30~90일 이상 보존, Silver는 PK 중복·결측·코드 표준화 규칙 20개 이상 적용
2. Gold는 도메인 KPI와 semantic layer를 연결하고 집계 오차 0.01% 이하 reconciliation을 일 단위 수행
3. 계층별 owner, SLA, lineage, backfill runbook을 등록해 장애 재처리 RTO 2시간 이하 목표 설정

**결론 (2줄):**
- 기술사 판단: 원시 데이터 보존과 공통 KPI 제공을 동시에 요구하면 메달리온, 단일 부서 단순 리포트는 2계층 구조도 가능
- 향후 방향: 메달리온은 데이터 제품, 데이터 메시, 레이크하우스 거버넌스와 결합해 도메인별 품질 책임 구조로 발전
