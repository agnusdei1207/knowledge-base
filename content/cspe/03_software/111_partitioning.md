## 미리 알고가기

- 파티셔닝은 한 테이블을 같은 데이터베이스 안에서 여러 조각으로 나눠 관리하는 기법임
- 파티션 프루닝은 질의 조건에 맞는 파티션만 읽어 전체 스캔 범위를 줄이는 동작임
- 로컬 인덱스는 각 파티션별로 따로 두는 인덱스이고, 글로벌 인덱스는 여러 파티션을 함께 보는 인덱스임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 파티셔닝은 분할 기준·프루닝·데이터 편중을 핵심 축으로 설명함
- 비교표는 범위·해시·리스트 파티셔닝의 분할 기준과 적합 환경을 대비함
- 대용량 테이블은 읽은 파티션 수·파티션 크기 편차로 검증함

## Ⅰ. 개요

- **정의/개념**: 파티셔닝은 큰 테이블이나 인덱스를 범위·해시·목록 기준으로 나눠 조회 범위와 유지보수 단위를 줄이는 물리 설계 기법임
- **배경/필요성**: 데이터 증가에 따른 전체 스캔과 보관·삭제 부담을 줄이기 위해 데이터 분포와 질의 조건에 맞는 파티션 키가 필요함

## Ⅱ. 특징

- 질의 조건에 파티션 키가 포함되면 옵티마이저가 조건과 무관한 파티션을 제외함
- 오래된 데이터 삭제와 보관과 재구성을 파티션 단위로 처리하기 쉬움
- 파티션 키가 질의 조건과 맞지 않으면 객체를 나눠도 성능 개선으로 이어지지 않을 수 있음
- 특정 파티션으로 데이터가 몰리면 편중과 관리 비용이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 파티셔닝 | 해시 파티셔닝 | 리스트 파티셔닝 |
|:---|:---|:---|:---|
| 분할 기준 | 날짜나 번호처럼 연속된 값 구간 | 해시 함수 결과 | 지역이나 상태처럼 명시적 값 집합 |
| 분할 결과 | 연속 값 구간별 파티션 | 해시 버킷별 파티션 | 명시한 값 집합별 파티션 |
| 한계 | 특정 기간에 데이터가 몰릴 수 있음 | 범위 조회에서 프루닝 효과가 약할 수 있음 | 값 관리가 늘어나면 운영이 복잡해짐 |
| 적합 환경 | 로그와 주문 이력 같은 시계열 데이터 | 균등 분산 쓰기가 필요한 데이터 | 지역별 또는 유형별 분리 데이터 |

> 요약: 범위는 연속 구간, 해시는 균등 분산, 리스트는 명시적 값 집합을 기준으로 파티션을 나눔.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 파티션 키 | 어떤 값 기준으로 데이터를 나눌지 정해 프루닝 효과와 편중 가능성을 좌우함 |
| 파티션 매핑 규칙 | 어떤 값이 어떤 파티션으로 가는지 정의해 저장 경로를 결정함 |
| 로컬 또는 글로벌 인덱스 | 파티션별 접근 효율과 관리 부담 사이의 균형을 정함 |
| 수명주기 작업 | 파티션 추가와 분리와 병합과 삭제를 통해 성장과 보관 정책을 관리함 |

> 요약: 파티션 키와 매핑 규칙이 데이터 위치를 결정하고 인덱스와 수명 주기 작업이 조회와 관리를 지원함.

## Ⅴ. 원리 및 절차 흐름도

1. **조건 추출**: 질의에서 파티션 키 조건을 확인함
2. **파티션 매핑**: 범위·해시·목록 규칙으로 대상 파티션을 계산함
3. **파티션 프루닝**: 조건과 무관한 파티션을 실행 계획에서 제외함
4. **대상 파티션 조회**: 선택된 파티션과 인덱스만 읽어 결과를 반환함

> 요약: 질의의 파티션 키를 매핑해 무관한 파티션을 제외하고 대상 파티션만 조회함.

## Ⅵ. 실무 사례

1. 주문 이력 DB는 날짜 범위 파티셔닝을 적용하고 읽은 파티션 수·p95 조회 지연을 확인함
2. 이벤트 DB는 해시 파티션의 분포를 조정하고 파티션 크기 편차·최대 요청 비율을 확인함

## Ⅶ. 결론

- 파티셔닝은 질의 프루닝과 데이터 분산을 함께 만족하는 파티션 키를 선택해야 함
