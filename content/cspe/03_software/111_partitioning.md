## 미리 알고가기

- 파티셔닝은 하나의 큰 테이블을 기준에 따라 논리적 또는 물리적으로 분할하는 기법임
- 범위와 해시와 리스트 파티셔닝은 분할 기준과 질의 적합성이 다름
- 파티션 프루닝과 데이터 편중 관리가 성능 핵심임

## Ⅰ. 개요

- **정의/개념**: 파티셔닝은 대용량 테이블이나 인덱스를 날짜와 키 범위와 해시 값 같은 기준으로 여러 파티션으로 나누어 관리함으로써 조회 범위를 줄이고 관리 작업을 분산하는 데이터베이스 물리 설계 기법임
- **배경/필요성**: 데이터가 단일 객체로 계속 커지면 조회와 백업과 삭제와 재구성 비용이 모두 증가하므로, 관리와 성능을 함께 개선할 분할 구조가 필요함

## Ⅱ. 특징

- 파티션 프루닝으로 조회 범위를 줄여 I/O를 절감함
- 보관 주기와 아카이브와 삭제 작업을 단위별로 수행하기 쉬움
- 잘못된 분할 키 선택은 데이터 편중과 프루닝 실패를 유발함
- 전역 인덱스와 지역 인덱스 운영 정책에 따라 유지 비용이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 파티셔닝 | 해시 파티셔닝 | 리스트 파티셔닝 |
|:---|:---|:---|:---|
| 분할 기준 | 연속 값 범위 | 해시 값 분산 | 명시적 값 집합 |
| 강점 | 기간별 관리와 pruning 유리 | 균등 분산 유리 | 업무 구분 명확 |
| 한계 | 특정 구간 편중 가능 | 범위 조회 pruning 약함 | 값 관리 복잡 |
| 적합 업무 | 시계열·주기성 데이터 | 균등 분산 쓰기 | 지역·카테고리 분리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Partition Key | 데이터 분산과 질의 pruning 가능성을 결정하는 핵심 기준임 |
| Partition Map | 각 값이 어느 파티션에 속하는지 정의해 저장 경로를 정함 |
| Local or Global Index | 파티션별 접근 경로와 유지 비용의 균형을 좌우함 |
| Lifecycle Operation | add, split, merge, drop 같은 관리 작업을 효율화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 분포/질의 분석  | --> | 분할 키 선택    | --> | 파티션 생성    | --> | pruning 효과 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **분포와 질의 분석**: 데이터 분산과 대표 필터 조건을 확인함
2. **분할 키 선택**: 편중과 pruning 효과를 함께 고려함
3. **파티션 생성**: 범위와 해시와 리스트 구조를 적용함
4. **pruning 효과 검증**: 실제 조회 범위 축소 여부를 측정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 파티션 키가 질의 조건과 맞지 않으면 객체만 나뉘고 실제 성능 향상은 거의 없을 수 있음
   - 해결방안: filter predicate 기반으로 키를 선정하고 pruning ratio와 scanned partition count로 검증함
2. 문제: 특정 파티션에 데이터가 몰리면 관리 분산 대신 hotspot만 심해질 수 있음
   - 해결방안: skew monitoring과 repartition plan을 운영하고 partition size variance와 hot partition rate로 검증함
3. 문제: 파티션 수를 과도하게 늘리면 통계와 인덱스와 관리 작업 오버헤드가 커질 수 있음
   - 해결방안: partition count budget을 두고 metadata overhead와 maintenance window duration으로 검증함

## Ⅶ. 적용 사례

- 로그성 대용량 테이블에서는 분할 키를 질의 조건에 맞추고 확인 지표는 pruning ratio와 scanned partition count임
- 대규모 주문 DB에서는 편중 감시를 운영하고 확인 지표는 partition size variance와 hot partition rate임
- 장기 보관 데이터 환경에서는 파티션 수 예산을 관리하고 확인 지표는 metadata overhead와 maintenance window duration임

## Ⅷ. 결론

파티셔닝의 효과는 분할 자체보다 실제 질의 pruning과 관리 단위 분리에 맞는 키를 고르는 데서 결정됨.
