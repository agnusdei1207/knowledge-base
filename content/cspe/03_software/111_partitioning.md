## 미리 알고가기

- 파티셔닝은 한 테이블을 같은 데이터베이스 안에서 여러 조각으로 나눠 관리하는 기법임
- 파티션 프루닝은 질의 조건에 맞는 파티션만 읽어 전체 스캔 범위를 줄이는 동작임
- 로컬 인덱스는 각 파티션별로 따로 두는 인덱스이고, 글로벌 인덱스는 여러 파티션을 함께 보는 인덱스임

## Ⅰ. 개요

- **정의/개념**: 파티셔닝은 하나의 큰 테이블이나 인덱스를 범위나 해시나 목록 기준으로 여러 파티션으로 나눠 저장하고 관리해 조회 범위를 줄이고 유지보수 단위를 분리하는 물리 설계 기법임.
- **배경/필요성**: 데이터가 커질수록 하나의 거대한 객체로 관리하면 조회와 보관과 삭제 작업이 모두 무거워지므로, 데이터 분포와 질의 조건에 맞춰 관리 단위를 나눌 필요가 있음.

## Ⅱ. 특징

- 질의 조건에 파티션 키가 포함되면 optimizer가 조건과 무관한 파티션을 pruning함
- 오래된 데이터 삭제와 보관과 재구성을 파티션 단위로 처리하기 쉬움
- 파티션 키가 잘못되면 객체만 나뉘고 실제 성능 개선은 거의 없을 수 있음
- 특정 파티션으로 데이터가 몰리면 편중과 관리 비용이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 파티셔닝 | 해시 파티셔닝 | 리스트 파티셔닝 |
|:---|:---|:---|:---|
| 분할 기준 | 날짜나 번호처럼 연속된 값 구간 | 해시 함수 결과 | 지역이나 상태처럼 명시적 값 집합 |
| 분할 결과 | 연속 값 구간별 파티션 | 해시 bucket별 파티션 | 명시한 값 집합별 파티션 |
| 한계 | 특정 기간에 데이터가 몰릴 수 있음 | 범위 조회에서 프루닝 효과가 약할 수 있음 | 값 관리가 늘어나면 운영이 복잡해짐 |
| 잘 맞는 업무 | 로그와 주문 이력 같은 시계열 데이터 | 균등 분산 쓰기가 필요한 데이터 | 지역별 또는 유형별 분리 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 파티션 키 | 어떤 값 기준으로 데이터를 나눌지 정해 프루닝 효과와 편중 가능성을 좌우함 |
| 파티션 매핑 규칙 | 어떤 값이 어떤 파티션으로 가는지 정의해 저장 경로를 결정함 |
| 로컬 또는 글로벌 인덱스 | 파티션별 접근 효율과 관리 부담 사이의 균형을 정함 |
| 수명 주기 작업 | 파티션 추가와 분리와 병합과 삭제를 통해 성장과 보관 정책을 관리함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 분포/질의 분석  | --> | 파티션 키 선택  | --> | 파티션 생성    | --> | 프루닝 효과 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **분포와 질의 분석**: 데이터 분포와 대표 조회 조건을 확인함
2. **파티션 키 선택**: 프루닝 효과와 데이터 편중을 함께 고려해 키를 고름
3. **파티션 생성**: 조회 조건과 데이터 분포에 따라 범위·해시·리스트 구조를 적용함
4. **프루닝 효과 검증**: 실제로 읽는 파티션 수가 줄었는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 로그와 주문 이력처럼 기간 조건이 반복되는 대용량 테이블에서는 범위 파티셔닝이 효과적이지만 질의 조건이 파티션 키를 타지 않으면 이득이 없으므로 읽은 파티션 수와 평균 조회 시간을 기준으로 확인함.
2. 데이터 편중이 생기기 쉬운 환경에서는 파티션 수만 늘리지 말고 분포를 함께 봐야 하므로 파티션별 크기 편차와 가장 뜨거운 파티션의 요청 비율로 확인함.

## Ⅶ. 결론

파티셔닝의 효과는 객체를 나누는 행위 자체보다 질의 프루닝과 관리 단위 분리를 동시에 만족하는 키를 고르는 데서 결정됨.
