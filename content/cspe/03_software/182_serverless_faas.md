## 미리 알고가기

- 서버리스 컴퓨팅은 서버가 없다는 뜻이 아니라 인프라 프로비저닝과 확장을 플랫폼이 담당하는 실행 모델임
- FaaS는 이벤트를 함수 실행 단위와 연결하고 호출량에 따라 인스턴스를 배정하는 서버리스 유형임
- 콜드 스타트는 사용 가능한 인스턴스가 없어 런타임과 함수를 초기화하는 지연임
- 함수 상태는 실행 인스턴스에 의존하지 않고 데이터베이스·객체 저장소 같은 외부 서비스에 보관함
- 이벤트 전달의 재시도·중복 가능성에 대비해 함수 연산의 멱등성을 설계해야 함

## 작성 근거(검토용)

- 서버리스·FaaS는 이벤트 트리거, 함수 인스턴스, 자동 확장, 외부 상태, 실행 제약을 핵심 축으로 설명함
- 비교표는 실행 단위·플랫폼 제어·적합 조건의 정확히 3개 축으로 선택 조건을 제시함
- 절차는 이벤트가 함수 인스턴스에 배정되고 결과와 실행량이 기록되는 실제 호출 순서를 따름

## Ⅰ. 개요

- **정의/개념**: 서버리스 컴퓨팅은 플랫폼이 실행 인프라를 할당·확장하고 FaaS가 이벤트마다 함수 코드를 실행하는 클라우드 실행 모델임
- **배경/필요성**: 요청량 변동이 큰 단기 작업을 서버 용량 관리와 분리하기 위해 이벤트 단위 실행·자동 확장 구조가 필요함

### 쉽게 이해하기 (학습용)
- 이벤트가 오면 함수 인스턴스를 실행하고 사용량에 따라 회수하는 서비스임

## Ⅱ. 특징

- HTTP·메시지·파일·스케줄 이벤트가 함수 호출을 시작함
- 플랫폼이 호출량에 따라 함수 인스턴스를 생성·재사용·회수함
- 함수는 외부 저장소에 상태를 두고 재시도에도 같은 결과를 내도록 구성함
- 실행 시간·메모리·동시성·네트워크 제약과 콜드 스타트를 설계에 반영해야 함

### 쉽게 이해하기 (학습용)
- 서버 관리는 줄지만 실행 한도·콜드 스타트·외부 상태 저장을 설계해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | FaaS | 컨테이너 서비스 |
|:---|:---|:---|
| 실행 단위 | 이벤트에 따라 생성·재사용·회수되는 함수 | 배포 정책에 따라 유지되는 장기 실행 서비스 |
| 플랫폼 제어 | 런타임·확장·실행 한도는 플랫폼, 상태는 외부 서비스가 담당 | 이미지·네트워크·자원·상태 정책을 사용자가 직접 정의 |
| 적합 조건 | 짧고 독립적인 이벤트 작업 | 지속 연결·장기 처리·세밀한 런타임 제어가 필요한 서비스 |

> 요약: FaaS는 이벤트마다 함수를 실행하고 플랫폼이 인스턴스 수명과 확장을 관리함.

### 쉽게 이해하기 (학습용)
- FaaS는 호출 단위 작업, 컨테이너 서비스는 계속 요청을 받는 실행 단위에 적합함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 소스 | HTTP 요청·메시지·파일 변경·스케줄을 생성함 |
| 트리거·이벤트 라우터 | 이벤트 조건을 평가해 대상 함수와 호출 방식을 결정함 |
| 함수 관리 계층 | 코드 버전·환경 변수·권한·동시성 정책을 관리함 |
| 격리 런타임 | 함수 인스턴스를 초기화하고 제한된 자원에서 코드를 실행함 |
| 외부 상태 서비스 | 함수 간 공유 상태와 실행 결과를 보존함 |
| 관측·과금 계층 | 호출 수·실행 시간·오류·재시도 내역을 기록함 |

```text
이벤트 소스 -> 트리거 -> 함수 관리 계층 -> 격리 런타임 -> 외부 상태
                               |
                               +-> 로그·메트릭·실행량
```

> 요약: 트리거가 이벤트를 함수에 연결하고 런타임은 외부 상태를 사용해 독립 실행함.

### 쉽게 이해하기 (학습용)
- 이벤트·트리거·함수 런타임·외부 상태가 서버리스 실행 경로를 이룸

## Ⅴ. 원리 및 절차 흐름도

```text
이벤트 수신 -> 권한·규칙 확인 -> 인스턴스 선택·초기화 -> 함수 실행 -> 결과·실행량 기록
```

1. **이벤트 수신**: 트리거가 HTTP·메시지·파일 변경 이벤트를 수신함
2. **호출 판정**: 라우터가 이벤트 규칙과 함수 실행 권한을 확인함
3. **인스턴스 배정**: 가용 인스턴스를 재사용하거나 새 런타임을 초기화함
4. **함수 실행**: 이벤트를 입력으로 처리하고 필요한 상태를 외부 서비스에 저장함
5. **결과 기록**: 응답·오류·재시도 상태와 실행 시간을 관측 계층에 남김

> 요약: 이벤트 조건과 권한을 확인한 뒤 함수 인스턴스를 배정하고 실행 결과와 사용량을 기록함.

### 쉽게 이해하기 (학습용)
- 이벤트를 받아 권한을 확인하고 실행한 뒤 결과와 비용 신호를 남김

## Ⅵ. 실무 사례

1. 이미지 업로드는 FaaS로 메타데이터를 추출하고 p95 호출 지연·실패율을 확인함
2. 큐 기반 주문 처리는 함수 멱등키로 중복 실행을 제어하고 재시도 건수·처리 지연을 확인함

### 쉽게 이해하기 (학습용)
- 독립 실행 업무에서 중복·지연·콜드 스타트를 측정함

## Ⅶ. 결론

- FaaS는 이벤트 작업이 짧고 독립적이며 콜드 스타트·실행 한도·외부 상태를 수용할 때 적용함

### 쉽게 이해하기 (학습용)
- 플랫폼 제약을 업무가 수용할 수 있는지가 선택 기준임
