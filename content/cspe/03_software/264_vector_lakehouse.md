## Ⅰ. 개요
- **정의**: 데이터 레이크하우스에 벡터 인덱스·유사도 검색을 통합하여 정형·비정형·벡터 데이터를 단일 플랫폼에서 관리하는 아키텍처
- **배경/필요성**: RAG·추천 등 AI 워크로드가 벡터 검색을 요구하나 별도 벡터 DB 운영은 데이터 사일로와 동기화 비용을 유발함
- **비유**: 도서관(레이크하우스)에 의미 기반 검색 엔진(벡터 인덱스)을 내장하여 별도 검색 서비스 없이 탐색하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 레이크하우스 진화 방향 이해 | 벡터 인덱스 통합 구조 | 독립 벡터 DB와의 차이를 대비 서술 |

> 요약: 벡터 레이크하우스는 레이크하우스에 벡터 검색을 내장하여 AI 워크로드를 통합 지원하는 아키텍처임

## Ⅱ. 구성요소
```text
[Data Sources] --Ingestion--> [Storage Layer]
                                   |
                    +--------------+--------------+
                    |              |              |
                    v              v              v
              [Table Format]  [Vector Index]  [Metadata Catalog]
                    |              |              |
                    v              v              v
              [SQL Engine]  [ANN Search]    [Unified Query]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Table Format | Delta/Iceberg 등 ACID 지원 테이블 포맷으로 정형 데이터를 저장함 | 도서관의 정리된 서가 |
| Vector Index | 임베딩 벡터에 ANN 인덱스(HNSW, IVF)를 구축하여 유사도 검색을 지원함 | 서가 옆 의미 색인 |
| Unified Query | SQL과 벡터 검색을 단일 쿼리로 결합하여 하이브리드 질의를 처리함 | 키워드+의미 통합 검색창 |

> 요약: 테이블 포맷·벡터 인덱스·통합 쿼리 엔진이 정형과 벡터 데이터를 단일 플랫폼에서 처리함

## Ⅲ. 절차
```text
데이터 수집 --> 임베딩 생성 --> 인덱스 구축 --> 하이브리드 질의
    |              |              |              |
    v              v              v              v
  ETL/스트림   모델추론      ANN인덱싱     SQL+벡터결합
```
- 1단계: 정형·비정형 데이터를 레이크하우스 스토리지에 적재함
- 2단계: 비정형 데이터에 임베딩 모델을 적용하여 벡터를 생성함
- 3단계: 생성된 벡터에 ANN 인덱스를 구축하고 메타데이터와 연결함
- 4단계: SQL 필터와 벡터 유사도를 결합한 하이브리드 질의를 수행함

> 요약: 적재-임베딩-인덱싱-질의 4단계로 통합 벡터 레이크하우스를 운영함

## Ⅳ. 문제점
- 인덱스 갱신 지연: 대규모 벡터 인덱스 재구축에 시간이 소요됨 — 실시간 데이터 반영이 지연됨
- 쿼리 최적화 복잡도: SQL과 ANN의 실행 계획 통합이 미성숙함 — 질의 성능 예측이 곤란함
- 임베딩 모델 종속: 모델 변경 시 전체 벡터 재생성이 필요함 — 운영 비용이 급증함

> 요약: 인덱스 갱신·쿼리 최적화·모델 종속이 벡터 레이크하우스의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 증분 인덱스 갱신(Incremental Indexing) 기법으로 재구축 비용을 절감
2. 중기: 비용 기반 옵티마이저에 벡터 검색 비용 모델을 통합
3. 장기: 임베딩 버전 관리 체계를 도입하여 모델 교체 시 점진적 마이그레이션을 지원

> 요약: 증분 인덱싱-옵티마이저 통합-임베딩 버전 관리 순으로 성숙도를 높일 필요

## Ⅵ. 전망
- 발전 방향: 멀티모달 임베딩을 지원하는 범용 AI 데이터 플랫폼으로 확장될 것임
- 기술사적 판단: 독립 벡터 DB는 특수 용도로 남고 범용 워크로드는 레이크하우스에 통합될 것임
- 기술사 제언: 데이터 플랫폼 현대화 시 벡터 검색 통합 요건을 아키텍처 설계에 반영할 필요
