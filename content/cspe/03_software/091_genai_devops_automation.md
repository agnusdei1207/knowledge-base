# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 시스템 개발·운영 전 과정(DevOps)에 생성형 AI(LLM)를 결합해 코딩·테스트·배포·운영을 지능화하는 자동화 체계
- **왜 필요한가**: CI/CD 파이프라인이 자동화되었지만, 여전히 스크립트 작성, 장애 로그 분석, 테스트 케이스 생성 등에는 사람의 개입이 필수적이다. GenAI는 이 인지적 작업을 자동화해 병목을 없앤다.
- **핵심 직관**: 기존 DevOps가 "정해진 파이프라인을 기계가 알아서 돌리는 것"이라면, GenAI DevOps는 "파이프라인 자체를 AI가 이해하고 장애 원인 분석과 대처 코드까지 짜주는 것"이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 생성형 AI (GenAI) | 프롬프트를 이해하고 코드·문서를 생성하는 모델 | 능숙한 부사수 |
| AIOps | AI를 활용한 IT 운영 (기존은 머신러닝 위주) | 로그 감시 카메라 |
| GenAI DevOps | GenAI를 SDLC 전반에 결합한 지능형 자동화 | 코드 짜는 자동화 로봇 |

## 깊이 이해
- **배경·문제의식**: MSA 확산으로 배포 빈도가 하루 10회 이상으로 늘고 인프라가 복잡해지면서, 장애 발생 시 원인 추적과 복구에 많은 시간이 소요됨.
- **작동 원리**: 
  - **계획/코딩**: GitHub Copilot 등이 개발자의 주석을 읽고 코드를 생성.
  - **테스트**: 소스코드를 분석해 Edge case를 포함한 단위 테스트 코드 자동 생성.
  - **배포/인프라**: 자연어 요구사항을 Terraform 등의 IaC 코드로 변환.
  - **운영/모니터링**: Datadog 등에서 에러 발생 시, LLM이 스택 트레이스와 과거 로그를 분석해 RCA(근본 원인 분석)와 해결 스크립트 제시.
- **비유**: 공장 자동화(DevOps)에 설계도면을 읽고 기계 고장 원인을 분석하는 지능형 AI 반장(GenAI)을 투입한 것.
- **구체 예시**: 서버 메모리 누수 발생 시 기존에는 엔지니어가 로그를 2시간 동안 뒤졌다면, GenAI는 에러 알림 직후 "Redis 연결 누수 발생. [해결 코드]를 적용하세요"라고 1분 만에 제시.
- **흔한 오해·주의점**: AI가 만든 IaC 코드나 장애 복구 스크립트는 환각(Hallucination)의 위험이 있으므로 반드시 사람의 승인(Human-in-the-loop) 과정이나 안전 장치(Guardrail)를 거쳐야 한다.

## 연결 개념
- **플랫폼 엔지니어링 (IDP)**: GenAI가 만든 결과물을 통합하고 안전하게 배포하는 플랫폼 기반
- **LLMOps**: LLM 자체의 생명주기를 관리하는 DevOps (GenAI DevOps와 방향이 반대)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 생성형 AI 기반 DevOps는 SDLC 전 과정의 인지적 병목(코드 작성, 로그 분석, 스크립트 생성)을 지능형 모델로 해소하는 차세대 자동화 체계이다.
> 2. **가치**: 기존 CI/CD가 절차의 자동화였다면, GenAI 결합은 인지 판단의 자동화를 통해 리드 타임 단축과 MTTR(평균 복구 시간)을 혁신적으로 개선한다.
> 3. **판단 포인트**: 환각에 의한 오작동 방지를 위해 프롬프트 엔지니어링, Human-in-the-loop, 가드레일 설계가 보안 및 안정성 확보의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SDLC 전 단계에서 GenAI의 역할 식별 | 계획·코딩·테스트·배포·운영 단계별 AI 적용 방안 (IaC 생성, RCA 분석 등) | 단순 챗봇 활용 수준의 얕은 서술 |
| AI 적용에 따른 부작용 및 통제 방안 | 환각(Hallucination), 보안(코드 유출), Human-in-the-loop, Guardrail | 완벽한 무인 자동화로 단정 |

> 요약: 각 DevOps 단계별 GenAI 적용 방안과 파생되는 리스크(환각·보안) 통제 체계를 균형 있게 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 생성형 AI 기반 DevOps는 기계학습 모델(LLM)을 활용해 소프트웨어 생명주기(SDLC) 전반의 개발·테스트·운영 작업을 지능적으로 자동화하는 체계임
- 배경: 클라우드 네이티브·MSA 환경에서 인프라 복잡도가 기하급수적으로 증가하여 기존 스크립트 기반 자동화의 한계 노출
- 필요성: 코드 생성부터 배포 스크립트(IaC) 작성, 장애 근본 원인 분석(RCA)까지 인지적 작업을 자동화해 배포 빈도 향상 및 MTTR 50% 이상 단축 필요

---

## Ⅱ. 구조 및 구성요소

```text
User Request -> Prompt Manager -> LLM/Foundation Model -> GenAI Output
                                   |
                                   +-> RAG (기업 지식·로그) / Guardrail 통제
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Prompt Manager | 사용자 요구를 AI가 이해할 수 있는 컨텍스트로 변환 | 템플릿화, 파이프라인 연동 |
| Foundation Model | 코드·스크립트·테스트 케이스·RCA 리포트 생성 | 코드 특화 LLM (Copilot 등) |
| RAG / Knowledge Base | 기업 내부 코드베이스, 과거 장애 이력, 아키텍처 문서 주입 | 최신성·근거성 확보 |
| Guardrail | 생성된 코드의 취약점 스캔, 정책 위반 필터링, Human 승인 | 환각 방지, 보안 통제 |

> 요약: 프롬프트 관리자, LLM, RAG를 통해 지능적 출력을 만들고, 가드레일로 보안과 품질을 통제하는 구조임

---

## Ⅲ. 동작원리 및 흐름도

```text
개발/운영 요구 -> 컨텍스트 수집/프롬프트 증강 -> LLM 추론/생성 -> 정책 검증(Guardrail) -> 파이프라인 실행
```

- 1단계 [컨텍스트 수집]: 코드 작성기, CI/CD 로그, 모니터링 알람 등 환경 데이터 수집 및 프롬프트 증강
- 2단계 [LLM 생성]: 단위 테스트 코드, IaC 스크립트, 배포 전략, RCA 리포트 등 산출물 생성
- 3단계 [정책 검증]: 생성된 코드/스크립트의 보안 취약점 스캔(SAST) 및 권한(RBAC) 검증
- 4단계 [실행 및 승인]: 검증 통과 시 파이프라인 자동 실행, 중요 인프라 변경 시 Human-in-the-loop 승인 거침

> 요약: 상황 인식 후 코드를 생성하고, 반드시 보안 정책 검증과 승인 절차를 거쳐 안전하게 실행함

---

## Ⅳ. 특징

- 인지 자동화: 정해진 룰(Rule) 기반이 아닌, 컨텍스트를 이해하는 지능형 스크립트 생성 및 로그 추론 가능
- 리드 타임 단축: 자연어 요구사항을 코드로 즉시 변환하여 개발-테스트-배포 리드 타임(Lead Time for Changes) 획기적 단축
- 종속성 탈피: 특정 도구의 문법을 몰라도 자연어로 CI/CD 파이프라인이나 K8s 매니페스트 구성 가능

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 전통적 DevOps (Rule-based) | GenAI DevOps (LLM-based) | 선택 기준 |
|:---|:---|:---|:---|
| 처리 방식 | 정해진 파이프라인 스크립트 순차 실행 | 컨텍스트 기반 유연한 코드/스크립트 생성 | 복잡성, 가변성 |
| 문제 해결 | 대시보드 및 로그 수동 분석 | 에러 로그 기반 자동 RCA 및 복구 코드 제시 | MTTR 목표치 |
| 진입 장벽 | 도구별 스크립트(YAML, Groovy) 학습 필요 | 자연어 프롬프트 기반 선언적 요구 | 팀 기술 숙련도 |

> 요약: 정형화된 반복 작업은 전통적 DevOps를 유지하고, 신규 코드 생성과 복잡한 장애 추론에 GenAI를 도입함

**리스크·대응 (기본은 불릿):**
- 환각(Hallucination): 비정상 코드/스크립트 생성 → RAG 도입, 정적 검사(SAST) 파이프라인 필수 연동 (지표: 생성 코드 버그율)
- 보안 유출: 프롬프트를 통한 내부 소스코드 유출 → On-Premise LLM 사용, 데이터 마스킹 (지표: DLP 탐지 건수)
- 통제 상실: AI의 자의적 인프라 변경 → 인프라 변경 시 Human-in-the-loop 결재 의무화 (지표: 인가되지 않은 배포 건수)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 코딩/테스트 단계: IDE 연동 코드 어시스턴트 적용 및 PR(Pull Request) 시 코드 리뷰·테스트 코드 80% 자동 생성
2. 배포 단계: 자연어 기반 Terraform/Ansible 코드 생성 및 배포 파이프라인 자동 구성
3. 운영 단계: Datadog 등 APM과 LLM 연동, 장애 발생 시 스택 트레이스 분석 기반 RCA 리포트 즉시 발송

**결론 (2줄):**
- 기술사 판단: GenAI DevOps는 개발 생산성을 극대화하나, 생성물의 무결성을 100% 보장할 수 없으므로 강력한 Guardrail과 파이프라인 보안(DevSecOps) 결합 시에만 안전하다
- 향후 방향: 단순 코드 보조를 넘어 스스로 파이프라인을 수정하고 자율 복구하는 AI Agent 기반의 자율형 운영 체계로 진화할 것이다
