## 미리 알고가기

- 시계열 데이터는 타임스탬프와 측정값을 시간 순서로 기록한 데이터임
- 메트릭은 CPU 사용률·요청 수처럼 반복 측정하는 항목이고 태그는 서비스·인스턴스처럼 시계열을 구분하는 차원임
- 활성 시계열 수는 메트릭과 태그 값 조합으로 만들어지는 현재 시계열 개수이며 인덱스 메모리에 영향을 줌
- 다운샘플링은 원본을 분·시간 단위 통계값으로 축약하고 보존 정책은 원본·축약본의 유지 기간을 정함
- 늦게 도착한 데이터는 현재 쓰기 구간보다 과거 타임스탬프를 가진 표본으로 청크 병합 비용을 만들 수 있음

## 작성 근거(검토용)

- 시계열 DB는 시계열 식별자, 시간 파티션, 압축 청크, 태그 카디널리티, 다운샘플링·보존 정책을 핵심 축으로 설명함
- 비교표는 관계형 DB와 시계열 DB의 쓰기 구조·주요 조회·수명주기를 대비함
- 실무 사례는 관측성 메트릭에서 활성 시계열 수·메모리와 저장 증가율·범위 조회 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 시계열 데이터베이스는 타임스탬프·측정값·태그를 시간 파티션과 압축 청크로 저장하고 구간 집계·다운샘플링·보존 정책을 제공하는 데이터베이스임
- **배경/필요성**: 시스템 관측성처럼 연속 쓰기와 시간 구간 집계가 많은 데이터의 저장량·인덱스·보존 비용을 통제하기 위해 시간 축 전용 저장 구조가 필요함

### 쉽게 이해하기 (학습용)
- 시간 도장이 찍힌 측정값을 빠르게 쌓고 시간 구간별로 요약·보관하는 데이터베이스임

## Ⅱ. 특징

- 시간 파티션과 쓰기 버퍼로 연속 표본을 모아 청크 단위로 기록·압축함
- 시간 범위와 태그 조건을 결합해 최근 구간 조회·윈도 집계를 수행함
- 다운샘플링과 보존 정책으로 원본·축약본의 해상도와 저장 기간을 분리함
- 태그 값 조합이 늘면 활성 시계열 수와 인덱스 메모리가 증가하고 늦은 데이터는 청크 재처리 비용을 만듦

### 쉽게 이해하기 (학습용)
- 연속 쓰기와 시간 집계에는 강하지만 태그 종류가 폭증하면 색인과 메모리 비용이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 범용 관계형 DB | 시계열 DB |
|:---|:---|:---|
| 쓰기 구조 | 행 갱신과 트랜잭션 로그 중심 | 시간 파티션·쓰기 버퍼·압축 청크 중심 |
| 주요 조회 | 행 조건·조인·트랜잭션 조회 | 시간 구간·윈도 집계·최근값 조회 |
| 수명주기 | 삭제·파티션 정책을 별도 설계 | 다운샘플링·보존 정책을 기본 제공 |

> 요약: 관계형 DB는 행·관계·트랜잭션에, 시계열 DB는 시간 파티션·구간 집계·보존 정책에 초점을 둠.

### 쉽게 이해하기 (학습용)
- 관계형 DB는 업무 행을, 시계열 DB는 시간순 표본과 구간 집계를 중심으로 다룸

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시계열 식별자 | 메트릭과 태그 집합으로 표본이 속할 시계열을 구분함 |
| 쓰기 버퍼·시간 파티션 | 표본을 시간 구간별로 모아 순차 기록 단위를 만듦 |
| 압축 청크·시간 인덱스 | 타임스탬프·값을 압축하고 조회할 시간 범위를 찾음 |
| 태그 인덱스 | 서비스·인스턴스·지역 조건으로 시계열 후보를 좁힘 |
| 집계·보존 계층 | 해상도별 축약본을 만들고 기간이 지난 원본·축약본을 삭제함 |

```text
+-----------+      +-----------+      +-----------+
| 수집 에이전트 | ---> | 식별자·시간 파티션 | ---> | 압축·집계·보존 |
+-----------+      +-----------+      +-----------+
```

> 요약: 시계열 식별자와 시간 파티션이 표본을 배치하고 압축·집계·보존 계층이 해상도별 수명주기를 관리함.

### 쉽게 이해하기 (학습용)
- 측정 대상 이름표, 시간 서랍, 압축 묶음과 기간별 요약·삭제 장치로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 표본 수신      | --> | 시계열 식별    | --> | 파티션·청크 저장 | --> | 집계·보존 적용  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **표본 수신**: 메트릭 이름·태그·타임스탬프·측정값을 수신함
2. **시계열 식별**: 메트릭과 태그 집합으로 기존 시계열을 찾거나 새 시계열을 생성함
3. **파티션·청크 저장**: 타임스탬프의 시간 파티션에 표본을 배치하고 청크로 압축함
4. **구간 집계**: 규칙에 따라 분·시간 단위 통계값을 별도 시계열로 생성함
5. **보존 정책 적용**: 유지 기간이 지난 원본·축약 청크를 삭제함

> 요약: 메트릭·태그로 시계열을 찾고 시간 파티션에 압축 저장한 뒤 해상도별 집계·보존 정책을 적용함.

### 쉽게 이해하기 (학습용)
- 표본을 이름표와 시간 구간으로 모아 압축하고 오래된 원본은 요약본만 남김

## Ⅵ. 실무 사례

1. 컨테이너 관측성은 허용 태그와 카디널리티 한도를 적용하고 활성 시계열 수·인덱스 메모리를 확인함
2. API 지연 메트릭은 해상도별 다운샘플링·보존 정책을 적용하고 일일 저장 증가량·p95 범위 조회 지연을 확인함

### 쉽게 이해하기 (학습용)
- 관측성 메트릭에 적용하고 활성 시계열 수·범위 조회 지연·저장 증가율을 함께 확인함

## Ⅶ. 결론

- 시계열 DB는 쓰기 빈도·태그 카디널리티·조회 시간 범위와 원본·축약본 보존 기간을 기준으로 적용해야 함
- 태그 폭증·지연 도착·다운샘플링 오차를 감시하고 업무 해상도에 맞춰 보존 정책을 조정해야 함

### 쉽게 이해하기 (학습용)
- 측정 항목이 너무 늘거나 늦게 온 값이 빠지지 않는지 확인하며 요약 간격을 조절해야 함
