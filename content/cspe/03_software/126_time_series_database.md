## 미리 알고가기

- 시계열 데이터는 시간 순서대로 계속 쌓이는 측정값 데이터임
- 메트릭은 CPU 사용률, 요청 수처럼 시간에 따라 계속 기록하는 수치 지표임
- 태그는 장비명, 지역, 서비스명처럼 데이터를 구분하는 꼬리표임
- 다운샘플링은 오래된 원본을 분 단위, 시간 단위처럼 더 거친 값으로 줄여 저장하는 방식임
- 보존 주기는 데이터를 얼마 동안 남길지 정한 규칙임

## Ⅰ. 개요

- **정의/개념**: 시계열 데이터베이스는 timestamp·측정값·tag를 시간 순서로 저장하고 시간 구간 필터·downsampling·보존 정책을 제공하는 데이터베이스임
- **배경/필요성**: 관측성, 설비 모니터링, 금융 시세처럼 쓰기는 매우 많고 조회는 시간 범위 중심인 데이터는 범용 데이터베이스로 처리하면 저장 비용과 조회 비용이 빠르게 커짐

## Ⅱ. 특징

- 시간 순서 쓰기와 최근 구간 조회에 강함
- 압축, 다운샘플링, 보존 주기로 저장 비용을 다루기 좋음
- 태그 기반 필터와 집계 함수가 자주 쓰임
- 태그 종류가 지나치게 많아지면 메모리와 인덱스 부담이 급격히 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 범용 관계형 DB | 시계열 DB |
|:---|:---|:---|
| 저장 관점 | 다양한 업무를 함께 처리함 | 시간 데이터 처리에 집중함 |
| 잘 맞는 조회 | 트랜잭션과 일반 조건 검색 | 시간 구간 조회와 집계 |
| 저장·수명주기 | 범용 행·인덱스·트랜잭션 관리 | 시간 순서 압축·retention·downsampling 관리 |
| 주의점 | 대량 시계열에서 비용이 커질 수 있음 | 복잡한 관계 질의는 제한될 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 측정값 저장부 | 시간과 값을 묶어 빠르게 기록함 |
| 태그 인덱스 | 장비, 지역, 서비스별 필터를 돕는 기준임 |
| 집계 계층 | 분, 시간, 일 단위 요약 값을 만듦 |
| 보존 정책 | 오래된 원본을 지우거나 축약값으로 바꿈 |

```text
+-----------+      +-----------+      +-----------+
| 수집 에이전트 | ---> | 시계열 저장부 | ---> | 집계/보존 계층 |
+-----------+      +-----------+      +-----------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 시간값 수집     | --> | 시간 순서 저장   | --> | 집계와 압축 수행 | --> | 보존 주기 적용  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **시간값 수집**: 메트릭과 이벤트를 시간 정보와 함께 받음
2. **시간 순서 저장**: 쓰기 성능이 나도록 시간 축 기준으로 저장함
3. **집계와 압축 수행**: 오래된 데이터는 요약하고 압축함
4. **보존 주기 적용**: 보관 기간이 지난 원본은 삭제하거나 축약본으로 대체함

## Ⅵ. 실무 적용 및 유의점

1. 관측성 지표처럼 태그가 많은 데이터는 태그 설계를 느슨하게 두면 메모리가 급격히 늘어나므로 활성 시계열 수와 메모리 사용량으로 태그 구조를 계속 조정함
2. 센서 원본을 오래 쌓는 환경은 보존 주기가 없으면 저장 비용이 통제되지 않으므로 축약 단계를 미리 정하고 저장 증가율과 기간별 조회 시간을 함께 점검함

## Ⅶ. 결론

시계열 DB의 핵심은 데이터가 많다는 사실보다 시간 범위 조회와 보존 비용을 함께 다루는 구조를 갖추는 데 있음.
