## Ⅰ. 개요
- 정의: 컨테이너 오케스트레이터가 다양한 스토리지 시스템을 노출하도록 하는 표준임
- 배경: K8s 코어 코드와 스토리지 드라이버의 분리(Out-of-tree)를 통한 유지보수성 향상
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 구성 요소 | Controller, Node Service | 높음 |
| 리소스 | PV, PVC, StorageClass | 매우높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ Pod ] -> [ PVC ] -> [ PV ] -> [ Storage Class ]
                                      |
  [ CSI Driver ] <--- (표준 RPC) --- [ Storage Vendor ]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| PV | 실제 스토리지 자원을 추상화한 객체 | 실제 토지 |
| PVC | 사용자가 필요한 스토리지 사양을 요청하는 객체 | 토지 대여 신청서 |
| StorageClass | 동적 프로비저닝을 위한 스토리지 템플릿 | 분양 옵션 |

> 요약: CSI RPC로 볼륨 생성·연결·마운트 기능을 오케스트레이터와 스토리지 드라이버 사이에 표준화함

## Ⅲ. 절차
- ASCII 흐름도
  [PVC 생성] -> [동적 볼륨 생성] -> [Node에 마운트] -> [Pod에서 사용]
    (사용자)        (Provision)       (Attach)          (Volume)

- 4단계 설명
1. 요청: 사용자가 PVC를 통해 필요한 용량과 성능(StorageClass)을 요청함
2. 생성: CSI 컨트롤러가 외부 스토리지 API를 호출하여 실제 볼륨을 생성함
3. 연결: 볼륨을 해당 워커 노드에 물리적으로 연결(Attach/Publish)함
4. 사용: 컨테이너 내부의 지정된 경로에 파일 시스템을 마운트하여 데이터 저장함

> 요약: PVC와 StorageClass를 기준으로 볼륨을 생성하고 노드 연결과 컨테이너 마운트를 수행함

## Ⅳ. 문제점
- 상태 유지(Stateful) 앱의 경우 노드 장애 시 볼륨 재연결 시간이 지연될 수 있음
- 멀티 클라우드 환경에서 스토리지 벤더마다 제공하는 기능의 편차가 존재함

## Ⅴ. 개선방안
- (단기) CSI 스냅샷 기능을 활용하여 정기적인 데이터 백업 및 복구 체계 구축함
- (중기) 로컬 NVMe 등 고성능 스토리지를 위한 CSI 드라이버 최적화 수행함
- (장기) 데이터 복제 기능을 포함한 클라우드 네이티브 스토리지(Rook 등) 도입함

## Ⅵ. 전망
- 'Data Gravity' 해결을 위한 지능형 데이터 배치 및 마이그레이션 기술 발전함
- 컨테이너 단위의 세밀한 암호화 및 접근 제어가 포함된 보안 CSI가 강조될 것임
