## Ⅰ. 개요
- 정의: 데이터베이스의 구조와 제약 조건에 관해 기술한 메타데이터의 집합
- 배경: 관점(사용자, 설계자, 시스템)에 따른 데이터 구조의 체계적 분리
| 구분 | 내용 |
|------|------|
| 출제 의도 | 외부(사용자), 개념(전체), 내부(물리) 스키마의 역할과 상호 관계 파악 |

## Ⅱ. 구성요소
  [ External A ] [ External B ] (User View)
           \      / 
         [ Conceptual ]         (Community View)
              | 
          [ Internal ]          (Physical View)
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| External | 개별 사용자나 응용 프로그램이 보는 논리적 구조 | 창문 |
| Conceptual | 전체적인 데이터베이스의 논리적 구조(개체, 관계) | 전체 평면도 |
| Internal | 실제 저장 장치에서의 물리적 저장 구조 | 기초 공사 |
> 요약: 데이터베이스의 논리적/물리적 청사진 제공

## Ⅲ. 절차
  Request -> External -> Conceptual -> Internal -> Data
1. External View: 사용자가 본인 권한에 맞는 데이터 요청
2. Conceptual Mapping: 논리적 전체 스키마와 대조 및 경로 파악
3. Internal Mapping: 물리적 파일 위치 및 인덱스 정보 획득
4. Data Access: 실제 디스크 블록에서 데이터 로드
> 요약: 3단계 계층 구조를 통한 데이터 독립성 및 보안 기능 수행

## Ⅳ. 문제점
- 스키마 변경 시 응용 프로그램과의 일관성 유지 부담
- 대규모 시스템에서 복잡한 매핑 정보 관리의 난해함

## Ⅴ. 개선방안
- 데이터 사전(Data Dictionary)을 통한 통합 스키마 관리
- 표준 데이터 모델(ISO/IEC 11179) 준수 및 거버넌스 체계 수립

## Ⅵ. 전망
- 데이터 메시 환경에서의 연합(Federated) 스키마 관리 및 동적 스키마 진화 기술 고도화
