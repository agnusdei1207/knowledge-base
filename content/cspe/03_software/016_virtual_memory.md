## 미리 알고가기

- 가상 메모리는 프로세스마다 독립된 주소 공간을 제공하는 메모리 관리 방식임
- 페이징은 고정 크기 페이지 단위로 메모리를 나누는 방식임
- 세그멘테이션은 코드와 데이터와 스택 같은 논리 단위로 메모리를 나누는 방식임

## Ⅰ. 개요

- **정의/개념**: 가상 메모리는 프로세스에 독립 주소 공간을 제공하고 실제 물리 메모리에는 필요한 부분만 적재하는 관리 기법이며, 대표 방식으로 페이징과 세그멘테이션이 있음
- **배경/필요성**: 여러 프로세스가 제한된 물리 메모리를 공유하려면 주소 공간 격리, 비연속 할당, 보조기억장치 연계가 필요함

## Ⅱ. 특징

- 프로세스마다 독립 주소 공간을 제공해 접근 범위와 격리 경계를 분리함
- 실제 물리 메모리보다 큰 논리 주소 공간을 제공함
- 페이징은 외부 단편화를 줄이지만 내부 단편화가 남을 수 있음
- 세그멘테이션은 코드·데이터·스택별 보호와 공유 범위를 표현하며, 가변 크기 할당으로 외부 단편화가 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 분할 기준 | 고정 크기 페이지 | 논리 의미 기반 가변 크기 세그먼트 |
| 주소 변환 | 페이지 번호와 오프셋 | 세그먼트 번호와 변위 |
| 단편화 특성 | 내부 단편화 가능 | 외부 단편화 가능 |
| 보호·공유 단위 | 고정 크기 페이지별 권한 설정 | 코드·데이터·스택 세그먼트별 권한 설정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Virtual Address Space | 프로세스가 보는 독립 주소 공간으로 프로그램 실행 편의와 메모리 보호의 기준이 됨 |
| Page or Segment Table | 논리 주소를 물리 위치로 매핑하며 변환 비용과 관리 복잡도를 좌우함 |
| Physical Frame | 실제 데이터가 적재되는 메모리 블록으로 가용 프레임 수가 시스템 수용 능력을 결정함 |
| Backing Store | 메모리에 없는 페이지를 보관해 논리 공간 확장을 가능하게 하는 보조기억장치 영역임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 논리 주소 생성  | --> | 테이블 변환    | --> | 적재 여부 확인 | --> | 메모리 접근    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **논리 주소 생성**: CPU가 프로세스의 가상 주소를 생성함
2. **테이블 변환**: 페이지 테이블 또는 세그먼트 테이블로 물리 위치를 찾음
3. **적재 여부 확인**: 메모리에 없으면 page fault 처리와 적재가 수행됨
4. **메모리 접근**: 변환된 물리 주소로 실제 데이터를 읽거나 씀

## Ⅵ. 실무 적용 및 유의점

1. 범용 운영체제와 메모리 집약 서버에서는 페이징 기반 가상 메모리를 쓰되 주소 변환 오버헤드와 페이지 폴트가 함께 커지지 않도록 TLB와 huge page와 working set 튜닝을 적용하고 TLB hit rate와 page fault rate와 swap I/O rate로 확인함
2. 논리 단위 보호나 구조 비교가 필요한 설계 검토에서는 세그멘테이션 관점도 함께 보되 외부 단편화와 관리 복잡도가 커질 수 있으므로 분할 기준과 memory utilization과 fragmentation ratio로 확인함

## Ⅶ. 결론

가상 메모리의 선택은 큰 논리 주소 공간 제공 자체보다 변환 비용과 단편화와 페이지 폴트를 어떤 구조로 통제할지에 달림.

## 작성 근거(검토용)

- 가상 메모리는 운영체제 기반이라는 평가보다 주소 공간 격리, 비연속 할당, 보조기억장치 연계라는 필요 조건으로 설명함
- 페이징과 세그멘테이션 비교는 분할 기준, 주소 변환, 단편화처럼 답안에서 검증 가능한 축으로 유지함
