## Ⅰ. 개요
- **정의**: 물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법
- **배경/필요성**: 물리 메모리 용량 한계를 넘어 다수 프로세스가 독립적 주소 공간을 사용하려면 추상화 계층이 필요함
- **비유**: 작은 책상(물리 메모리) 위에 필요한 서류만 올려놓고 나머지는 서랍(디스크)에 보관하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 추상화 원리 이해 | 페이지 테이블·TLB·페이지 폴트 흐름 | 가상 주소 → 물리 주소 변환 과정 정확히 기술 필요 |

> 요약: 물리 메모리를 추상화하여 프로세스별 독립 주소 공간과 용량 확장을 제공하는 기법임

## Ⅱ. 구성요소
```text
CPU --> Virtual Addr --> TLB --hit--> Physical Addr --> Memory
                          |
                         miss
                          |
                          v
                      Page Table --> Physical Addr
                          |
                       not present
                          v
                      Page Fault --> Disk(Swap)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Page Table | 가상 페이지 번호를 물리 프레임 번호로 매핑하는 테이블 | 좌석 배치표 |
| TLB | 페이지 테이블 캐시로 주소 변환을 가속하는 하드웨어 | 자주 쓰는 전화번호 단축키 |
| Page Fault | 요청 페이지가 물리 메모리에 없을 때 발생하는 인터럽트 | 서랍에서 서류를 꺼내오는 행위 |
| Swap Area | 물리 메모리 부족 시 페이지를 임시 저장하는 디스크 영역 | 서류 보관 서랍 |

> 요약: 페이지 테이블, TLB, 페이지 폴트, 스왑 영역으로 주소 변환과 용량 확장을 수행함

## Ⅲ. 절차
```text
가상주소 발생 --> TLB 조회 --> 페이지 테이블 참조 --> 물리주소 접근
```
- 1단계: CPU가 가상 주소를 생성하여 MMU로 전달
- 2단계: TLB에서 해당 가상 페이지 매핑 검색 (hit 시 4단계로 이동)
- 3단계: TLB miss 시 페이지 테이블 참조, 미적재 시 Page Fault 처리 후 디스크에서 적재
- 4단계: 획득한 물리 프레임 번호 + 오프셋으로 물리 메모리 접근

> 요약: 가상주소 생성-TLB 조회-페이지 테이블 참조-물리 접근 4단계로 동작함

## Ⅳ. 문제점
- 페이지 폴트 오버헤드: 디스크 I/O 발생 — 메모리 접근 대비 수만 배 지연
- TLB 미스 증가: 프로세스 수 증가 시 TLB 경합 — 주소 변환 지연 누적
- 메모리 단편화: 내부 단편화로 프레임 공간 낭비 — 유효 메모리 활용률 저하

> 요약: 페이지 폴트 지연, TLB 경합, 내부 단편화가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 프리페칭(Prefetching) 기법으로 페이지 폴트 빈도 감소
2. 중기: 대형 페이지(Huge Page) 적용으로 TLB 커버리지 확대 및 미스율 감소
3. 장기: 다단계 페이지 테이블 최적화 및 하드웨어 페이지 워커 성능 개선

> 요약: 프리페칭, 대형 페이지, 페이지 테이블 최적화 순으로 개선 필요

## Ⅵ. 전망
- 발전 방향: CXL 기반 메모리 풀링으로 물리 메모리 확장이 가속화되고 있음
- 기술사적 판단: 가상 메모리는 OS 핵심 기반이며 메모리 이종화 환경에서도 유지될 전망임
- 기술사 제언: 워크로드별 페이지 크기·스왑 정책을 튜닝하여 페이지 폴트를 최소화할 필요
