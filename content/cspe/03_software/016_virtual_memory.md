# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 물리적 RAM 크기의 한계를 극복하기 위해 디스크 스왑(Swap) 영역을 확장 메모리처럼 사용하고, 프로세스에게는 가짜(가상) 주소 공간을 독점 제공하는 추상화 기술.
- **왜 필요한가**: RAM이 8GB인데 10GB짜리 게임과 4GB짜리 브라우저를 동시에 실행하려면, 현재 당장 필요한 코드만 RAM에 올리고 안 쓰는 부분은 디스크에 내려놓는 "가짜 넓은 책상"이 필요하다.
- **핵심 직관**: 모든 직원(프로세스)에게 "당신 혼자 쓰는 64비트 크기의 거대한 개인 창고가 있다"고 사기를 친다. 직원이 물건을 찾으면, 실제로는 물류센터(디스크)에서 그때그때 퀵오토바이로 개인 창고(RAM)에 가져다주는 방식이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **MMU (Memory Management Unit)** | 가상 주소를 물리 주소로 실시간 변환해주는 CPU 내장 하드웨어 칩 | "가짜 창고 번호를 진짜 창고 번호로 번역해주는 안내원" |
| **페이징 (Paging)** | 메모리를 4KB 등 동일한 고정 크기(Page)로 쪼개어 관리하는 기법 | "모든 물건을 규격화된 A4 박스에 나누어 담기" |
| **세그멘테이션 (Segmentation)** | 메모리를 함수, 배열 등 논리적 의미 단위(가변 크기)로 쪼개어 관리하는 기법 | "침대, 냉장고 등 물건의 실제 크기대로 포장하기" |
| **단편화 (Fragmentation)** | 쪼개고 남거나 애매해서 못 쓰는 빈 메모리 공간 (내부/외부) | "박스 안의 빈 공간(내부), 또는 박스들 사이의 좁은 틈(외부)" |

## 깊이 이해
- **배경·문제의식**: 초기 컴퓨터는 프로그램을 메모리에 통째로 올려야만 실행할 수 있어 메모리 크기가 곧 프로그램 크기 한계였다. 또한, 여러 프로그램이 메모리에 함께 올라갈 때 주소가 충돌하는 문제가 있었다.
- **작동 원리**:
  1. 컴파일러는 프로그램이 0번지부터 시작한다고 가정한 가상 주소(Logical Address)로 코드를 생성한다.
  2. 실행 시, CPU가 가상 주소를 호출하면 MMU가 페이지 테이블을 참조하여 실제 물리 주소(Physical Address)로 변환한다.
  3. 물리 메모리에 해당 데이터가 없으면 Page Fault가 발생하여 디스크에서 가져온다.
- **단편화 문제 (페이징 vs 세그멘테이션)**:
  - **페이징**: 고정 크기이므로 남는 자투리 공간(내부 단편화) 발생. 단, 빈 프레임 어디든 들어갈 수 있어 외부 단편화는 0.
  - **세그멘테이션**: 가변 크기이므로 꽉 채워 담아 내부 단편화는 0. 단, 메모리에 들고 나다 보면 중간중간 크기가 안 맞아 못 쓰는 틈(외부 단편화)이 생김.
- **구체 예시**: 32비트 OS는 가상 주소 공간이 $2^{32}$ = 4GB로 제한되어, 아무리 RAM을 16GB를 꽂아도 프로세스 하나는 4GB까지만 쓸 수 있었다. 64비트는 이론상 16엑사바이트(EB)의 공간을 제공한다.
- **흔한 오해·주의점**: 세그멘테이션과 페이징 중 하나만 쓰는 것이 아니라, 현대 OS는 세그멘테이션으로 논리적 접근 권한(Code, Data 영역 보호)을 통제하고 그 하단을 다시 페이징으로 쪼개어 물리 메모리를 관리하는 혼합(Paged Segmentation) 방식을 쓴다.

## 연결 개념
- (020 TLB 참조) 페이지 테이블 참조 속도를 높이는 캐시
- (017 페이지 교체 알고리즘 참조) 메모리 부족 시 페이지 방출

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 가상 메모리는 디스크를 논리적으로 확장하여 물리 메모리의 한계를 극복하고, 프로세스별로 독립된 주소 공간을 제공하는 하드웨어-OS 통합 추상화 기법이다.
> 2. **가치**: 다중 프로그래밍 정도(MPD)를 획기적으로 높이고, 메모리 보호(Protection) 및 주소 충돌 방지를 달성한다.
> 3. **판단 포인트**: 메모리 분할 방식인 페이징(내부 단편화)과 세그멘테이션(외부 단편화)의 트레이드오프를 이해하고, TLB를 통한 주소 변환 성능 보완 구조를 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 물리 메모리 한계 극복 및 주소 변환 메커니즘 이해 | MMU 구조, 가상/물리 주소 매핑, Page Fault 발생 흐름 | 디스크 스왑만 강조하고 주소 보호/독립성 역할 누락 |
| 메모리 분할 관리 기법 비교 역량 | 페이징(고정 크기, 내부 단편화) vs 세그멘테이션(가변, 외부 단편화) 표 | 내부/외부 단편화 개념을 반대로 서술하는 오류 |

> 요약: 가상 메모리는 단순한 용량 확장이 아니라 주소 공간의 독립성과 보호를 제공하는 구조이며, 페이징과 세그멘테이션의 단편화 차이를 명확히 비교해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 가상 메모리는 프로세스가 물리 메모리보다 큰 연속된 주소 공간을 가진 것처럼 추상화하여, MMU를 통해 동적 주소 변환을 수행하는 관리 기법
- 배경: 물리 메모리의 크기 제약과 다중 프로세스 동시 적재 시 발생하는 주소 충돌 및 메모리 침범 문제
- 필요성: 시스템의 처리량(Throughput) 극대화, 프로세스 간 메모리 격리(Isolation) 확보, 연속적 메모리 할당의 한계 극복 필수

---

## Ⅱ. 구조 및 구성요소

```text
[CPU (가상 주소)] -> [MMU (TLB -> 페이지/세그먼트 테이블)] -> [RAM (물리 주소)]
                                       |
                       (Page Fault) -> [OS 개입] -> [디스크 Swap 영역]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 가상 주소 (Logical) | CPU가 생성하는 0번지부터 시작하는 프로세스 독립 주소 | 페이징 시 (페이지 번호 P, 오프셋 D)로 분할 |
| MMU (Memory Mgt Unit) | 가상 주소를 물리 주소로 실시간 매핑하는 H/W 칩 | 주소 변환 가속을 위해 내부에 TLB 캐시 탑재 |
| 매핑 테이블 | 페이지 테이블 또는 세그먼트 테이블을 통해 주소 매핑 정보 저장 | 커널 메모리에 위치하며, 유효/보호 비트 포함 |

> 요약: 가상 메모리 시스템은 CPU와 RAM 사이에 MMU와 테이블 구조를 개입시켜 동적 주소 변환과 메모리 보호를 동시에 달성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
가상 주소 요청 -> MMU TLB 캐시 확인 -> (Miss 시) 페이지 테이블 조회 -> 유효 비트(Valid Bit) 검사
  / 유효(1) -> 물리 프레임 주소 산출 -> RAM 접근
  / 무효(0) -> OS Page Fault Trap -> 디스크에서 페이지 스왑 -> 테이블 갱신 -> 명령어 재시작
```

- 1단계 [주소 변환 시도]: CPU가 특정 가상 주소를 요청하면 MMU가 매핑 테이블 참조
- 2단계 [가용성 및 권한 검사]: Valid Bit로 메모리 적재 여부를 확인하고, Protection Bit로 읽기/쓰기 권한 검증
- 3단계 [Page Fault 처리]: 물리 메모리에 데이터가 없으면 디스크에서 빈 프레임(또는 교체된 프레임)으로 페이지 복사
- 4단계 [물리 주소 접근]: 최종 산출된 물리 주소(프레임 번호 + 오프셋)를 통해 실제 RAM 데이터 접근

> 요약: 주소 변환은 H/W(MMU)가 빠르게 처리하고, 데이터가 부재할 때만 OS(커널)가 개입하여 디스크 스왑을 수행한다.

---

## Ⅳ. 비교 (페이징 vs 세그멘테이션)

| 비교 축 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | 선택 기준 (현대 OS 혼합 사용) |
|:---|:---|:---|:---|
| 분할 단위 | 고정 크기 (예: 4KB Page) | 가변 크기 (함수, 객체 단위 Segment) | 물리적 관리 용이성 vs 논리적 의미 보존 |
| 매핑 구조 | 페이지 번호(P) + 오프셋(D) | 세그먼트 번호(S) + 오프셋(D) + Limit 확인 | 세그멘테이션은 주소 초과(Limit) 검사 추가 필요 |
| 단편화 문제 | 내부 단편화 (페이지 자투리) | 외부 단편화 (메모리 파편화 빈 공간) | 버디 시스템(Buddy System)이나 압축(Compaction) 등 추가 대책 필요 |
| 공유 및 보호 | 코드/데이터 구분이 모호하여 보호 설정 까다로움 | 논리 단위 분할이므로 권한(R/W/X) 부여 용이 | 세그멘테이션 위에서 페이징을 수행하는 Paged Segmentation 활용 |

> 요약: 페이징은 외부 단편화를 없애 물리 메모리 관리에 뛰어나고, 세그멘테이션은 코드와 데이터를 분리해 보안 통제에 뛰어나다.

## Ⅴ. 심화 비교 및 적용 판단

**리스크·대응:**
- TLB 미스 및 다단계 테이블 접근 오버헤드: 64비트 주소 체계에서는 페이지 테이블 크기 자체가 기가바이트(GB) 단위로 커짐 → 다단계(Multi-level) 페이지 테이블 또는 해시(Inverted) 페이지 테이블 적용 + TLB 히트율 향상 (지표: TLB Miss Rate)
- 페이지 폴트 병목: 디스크 I/O 속도 한계로 시스템 전체 응답성 저하 → 예측 기반의 프리페이징(Prepaging) 및 고속 NVMe 스왑 영역 할당

**도입 후 점검 지표:**
- 성능: TLB Hit Ratio 95% 이상 유지 — 하드웨어 퍼포먼스 카운터
- 무결성: 세그먼트 Limit/권한 위반 발생 시 즉각적인 Segmentation Fault(SIGSEGV) 발생 및 격리 확인

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Huge Page (대용량 페이지) 적용: 대규모 DB(Oracle, PostgreSQL) 서버에서 4KB 대신 2MB/1GB 페이지를 사용하여 TLB 엔트리를 절약하고 TLB Miss 급감 달성
2. Paged Segmentation 혼합 모델: 논리적 영역(Code, Data, Stack) 통제는 세그멘테이션으로, 물리 프레임 관리는 페이징으로 처리하여 보안과 단편화 문제를 동시 해결
3. 메모리 압축(Zswap) 기법 융합: 디스크 스왑의 느린 I/O 한계를 극복하기 위해, 물리 메모리 일부 영역에 페이지를 압축하여 저장하는 기술을 가상 메모리 정책에 통합

**결론 (2줄):**
- 기술사 판단: 가상 메모리 성능의 핵심은 디스크 스왑 발생을 억제하는 동시에 MMU의 주소 변환(TLB Hit)을 고속화하는 것이므로 적절한 페이지 크기(Huge Page) 튜닝이 필수적이다.
- 향후 방향: 최근 CXL(Compute Express Link) 기술을 통해 원격 서버의 메모리를 로컬 가상 메모리 공간으로 투명하게 확장하는 메모리 풀링(Memory Pooling) 아키텍처로 진화하고 있다.
