## Ⅰ. 개요
- **정의**: 물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법
- **배경/필요성**: 프로세스마다 독립된 주소 공간을 보장하면서 물리 메모리 용량 제약을 극복해야 함
- **비유**: 작은 책상(물리 메모리)에 서랍(디스크)을 두고, 필요한 서류만 꺼내 놓고 작업하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주소 변환과 페이징 메커니즘 이해 | 페이지 테이블·TLB·페이지 폴트 처리 | 가상 주소와 물리 주소를 혼동하지 않을 것 |

> 요약: 가상 주소 공간으로 프로세스 격리와 물리 메모리 확장을 동시에 달성하는 기법임

## Ⅱ. 구성요소
```text
CPU --> Virtual Addr --> TLB --hit--> Physical Addr --> RAM
                          |
                         miss
                          v
                      Page Table --present--> Physical Addr
                          |
                        absent
                          v
                      Page Fault --> Disk --> RAM (swap in)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 페이지 테이블 | 가상 페이지 번호를 물리 프레임 번호로 매핑하는 자료구조 | 서류 색인표 |
| TLB | 최근 사용 매핑을 캐싱하는 고속 연관 메모리 | 자주 쓰는 서류를 올려둔 책상 위 트레이 |
| 페이지 폴트 핸들러 | 물리 메모리에 없는 페이지를 디스크에서 적재하는 OS 루틴 | 서랍에서 서류를 찾아 책상에 올리는 비서 |

> 요약: 페이지 테이블·TLB·페이지 폴트 핸들러로 주소 변환과 요구 페이징을 수행함

## Ⅲ. 절차
```text
가상주소 발생 --> TLB 조회 --> 페이지 테이블 조회 --> 페이지 폴트 처리
```
- 1단계: CPU가 가상 주소를 생성하여 MMU에 전달함
- 2단계: TLB에서 매핑을 검색하여 히트 시 물리 주소를 즉시 반환함
- 3단계: TLB 미스 시 페이지 테이블을 탐색하여 프레임 번호를 획득함
- 4단계: 페이지 부재 시 디스크에서 해당 페이지를 물리 메모리로 적재(swap in)함

> 요약: TLB-페이지 테이블-디스크의 계층적 탐색으로 주소를 변환함

## Ⅳ. 문제점
- 페이지 폴트 오버헤드: 디스크 I/O가 발생하여 메모리 접근 대비 수만 배 지연이 생김
- TLB 미스 증가: 워킹셋이 TLB 엔트리 수를 초과하면 매 접근마다 테이블 탐색이 반복됨
- 스래싱: 물리 메모리 부족으로 페이지 교체가 빈번하여 CPU 이용률이 급감함 (018 참조)

> 요약: 페이지 폴트 지연, TLB 미스, 스래싱이 가상 메모리의 성능 저하 요인임

## Ⅴ. 개선방안
1. 단기: 대용량 페이지(Huge Page) 적용으로 TLB 커버리지를 확대하여 미스율을 낮춤
2. 중기: 프리페칭 기법으로 예측된 페이지를 선제 적재하여 폴트 빈도를 감소시킴
3. 장기: 워킹셋 기반 적응형 메모리 할당으로 프로세스별 물리 프레임을 동적 조절하여 스래싱을 방지함

> 요약: 대용량 페이지, 프리페칭, 적응형 할당으로 가상 메모리 성능을 개선함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 풀링으로 물리 메모리 경계가 호스트 단위에서 랙 단위로 확장됨
- 기술사적 판단: 메모리 중심 아키텍처에서 가상 메모리 계층 재설계가 필수 과제임
- 기술사 제언: CXL·NUMA 환경에서 페이지 배치 정책을 지역성 기반으로 재수립할 필요
