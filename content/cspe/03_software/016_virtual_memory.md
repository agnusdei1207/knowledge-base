## Ⅰ. 개요
- **정의**: 물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법
- **배경/필요성**: 프로세스마다 독립 주소 공간을 보장하면서 물리 메모리를 효율 공유할 필요가 있음
- **비유**: 은행(물리 메모리)이 모든 고객(프로세스)에게 각자의 금고(가상 주소)를 제공하되 실제 금고는 공유하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OS 메모리 관리 역량 확인 | 페이지 테이블·TLB·페이지 폴트 처리 흐름 | 가상 주소 = 물리 주소로 혼동하지 않을 것 |

> 요약: 가상 주소와 물리 주소를 매핑하여 프로세스별 독립 메모리 공간을 제공하는 기법임

## Ⅱ. 구성요소
```text
CPU --> VA --> TLB --hit--> PA --> Physical Memory
                |                       ^
              miss                      |
                |                       |
                v                       |
           Page Table --valid-----------+
                |
             invalid
                |
                v
           Page Fault --> Disk I/O --> Page Load
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 페이지 테이블 | 가상 페이지 번호를 물리 프레임 번호로 매핑하는 자료구조 | 금고 번호 대조표 |
| TLB | 최근 매핑을 캐시하는 고속 연관 메모리 | 자주 쓰는 금고 키 보관함 |
| 페이지 폴트 핸들러 | 물리 메모리에 없는 페이지를 디스크에서 적재하는 OS 루틴 | 금고 열쇠가 없을 때 본점에 요청 |
| 스왑 영역 | 물리 메모리 부족 시 페이지를 임시 저장하는 디스크 공간 | 별도 창고 |

> 요약: TLB-페이지 테이블-스왑 영역으로 가상-물리 주소 매핑을 수행함

## Ⅲ. 절차
```text
주소 변환 요청 --> TLB 조회 --> 페이지 테이블 참조 --> 페이지 적재
```
- 1단계: CPU가 가상 주소(VA)를 생성하여 MMU에 전달
- 2단계: TLB에서 해당 VPN의 매핑을 조회하고 히트 시 물리 주소로 변환
- 3단계: TLB 미스 시 페이지 테이블을 탐색하여 유효 비트 확인
- 4단계: 유효하지 않으면 페이지 폴트 발생, 디스크에서 페이지 적재 후 테이블 갱신

> 요약: VA 생성-TLB 조회-페이지 테이블 참조-폴트 처리 순으로 주소를 변환함

## Ⅳ. 문제점
- 페이지 폴트 지연: 디스크 I/O 발생 — 메모리 접근 대비 수만 배 지연이 발생함
- 페이지 테이블 비대화: 64비트 주소 공간 — 단일 테이블 크기가 수 GB에 달함
- TLB 미스 오버헤드: 컨텍스트 스위치 시 TLB 플러시 — 스위치 직후 미스율 급증함

> 요약: 폴트 지연·테이블 비대화·TLB 미스가 가상 메모리의 주요 성능 병목임

## Ⅴ. 개선방안
1. 단기: 대용량 페이지(Huge Page) 사용으로 TLB 엔트리당 커버리지 확대 및 폴트 빈도 감소
2. 중기: 다단계 페이지 테이블(4-Level) 및 역 페이지 테이블로 메모리 사용량 절감
3. 장기: ASID(Address Space ID) 기반 TLB 태깅으로 컨텍스트 스위치 시 플러시 제거

> 요약: Huge Page, 다단계 테이블, ASID 태깅으로 가상 메모리 오버헤드를 저감함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 확장 시 가상 메모리 계층이 로컬-원격 DRAM-디스크로 다층화
- 기술사적 판단: 메모리 중심 컴퓨팅에서 가상 메모리의 주소 추상화 역할이 확대됨
- 기술사 제언: 워크로드 특성에 따라 페이지 크기·프리페치 정책을 차별 적용 필요
