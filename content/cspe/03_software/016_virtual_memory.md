## Ⅰ. 개요
- **정의**: 물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 관리 기법
- **배경/필요성**: 제한된 물리 메모리를 다수 프로세스가 독립적·안전하게 사용할 필요가 있음
- **비유**: 은행이 예금 전액을 금고에 보관하지 않고 필요 시 인출하는 지급준비 제도와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OS 메모리 관리 원리 | 페이지 테이블·TLB·요구 페이징 | 가상 주소와 논리 주소 혼동 금지 |

> 요약: 디스크를 보조 저장소로 활용하여 물리 메모리 용량 이상의 주소 공간을 제공하는 기법임

## Ⅱ. 구성요소
```text
CPU --> Virtual Addr --> MMU/TLB --> Physical Addr --> RAM
                          |  (miss)
                          v
                       Page Table --> Disk(Swap)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 페이지 테이블 | 가상 페이지→물리 프레임 매핑 정보를 저장함 | 도서관 목록 카드 |
| TLB | 최근 사용 매핑을 캐싱하여 주소 변환을 가속함 | 자주 쓰는 번호 단축 다이얼 |
| MMU | 가상 주소를 물리 주소로 하드웨어 변환함 | 우편번호 자동 분류기 |
| 스왑 영역 | 물리 메모리 부족 시 페이지를 저장하는 디스크 공간 | 창고 보관함 |

> 요약: MMU·TLB·페이지 테이블·스왑 영역이 주소 변환과 메모리 확장을 수행함

## Ⅲ. 절차
```text
가상주소 발생 --> TLB 조회 --> 페이지 테이블 조회 --> 페이지 폴트 처리
```
- 1단계: CPU가 가상 주소를 생성하여 MMU에 전달함
- 2단계: TLB에서 매핑을 조회하고, 히트 시 물리 주소로 변환함
- 3단계: TLB 미스 시 페이지 테이블을 탐색하여 매핑을 확인함
- 4단계: 페이지 폴트 발생 시 디스크에서 해당 페이지를 물리 메모리로 적재함(018 참조)

> 요약: 가상주소 → TLB → 페이지 테이블 → 페이지 폴트 처리 순서로 변환함

## Ⅳ. 문제점
- 스래싱: 물리 메모리 부족 시 페이지 교체가 반복되어 CPU 이용률이 급감함
- TLB 미스 오버헤드: 대규모 주소 공간에서 TLB 커버리지 부족으로 변환 지연이 발생함
- 메모리 단편화: 페이지 단위 할당 시 내부 단편화로 메모리가 낭비됨

> 요약: 스래싱, TLB 미스, 내부 단편화가 성능과 메모리 효율을 저하시킴

## Ⅴ. 개선방안
1. 단기: 워킹셋 기반 페이지 교체(018 참조)로 스래싱을 억제함
2. 중기: 대형 페이지(Huge Page)를 적용하여 TLB 커버리지를 확대함
3. 장기: 투명 대형 페이지(THP)·다단 페이지 테이블 최적화로 단편화를 완화함

> 요약: 워킹셋 관리 → 대형 페이지 → THP 최적화 순으로 개선함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 풀링으로 물리 메모리 확장 시 가상 메모리 관리 구조가 변화 중임
- 기술사적 판단: 프로세스 격리와 메모리 보호의 기반 기술로 OS 핵심 개념의 위상을 유지함
- 기술사 제언: 대용량 메모리 환경에서 페이지 테이블 오버헤드를 최소화하는 설계 검토가 필요함
