## 미리 알고가기

- 가상 메모리는 프로세스마다 독립된 주소 공간을 제공하는 메모리 관리 방식임
- 페이징은 고정 크기 페이지 단위로 메모리를 나누는 방식임
- 세그멘테이션은 코드와 데이터와 스택 같은 논리 단위로 메모리를 나누는 방식임
- TLB(Translation Lookaside Buffer): 최근 사용한 주소 변환 결과를 캐싱하는 하드웨어임

## 작성 근거(검토용)

- 가상 메모리는 주소 공간 격리·주소 변환·요구 적재라는 운영체제 역할로 설명함
- 페이징과 세그멘테이션은 분할·주소 변환 방식, 단편화 리스크, 보호·공유 단위로 비교함
- 주소 변환과 페이지 폴트 처리 흐름을 유지하고 사례는 페이징·논리 보호로 분리함

## Ⅰ. 개요

- **정의/개념**: 가상 메모리는 프로세스에 독립 주소 공간을 제공하고 실제 물리 메모리에는 필요한 부분만 적재하는 관리 기법이며, 대표 방식으로 페이징과 세그멘테이션이 있음
- **배경/필요성**: 여러 프로세스가 제한된 물리 메모리를 공유하려면 주소 공간 격리, 비연속 할당, 보조기억장치 연계가 필요함

## Ⅱ. 특징

- 프로세스마다 독립 주소 공간을 제공해 접근 범위와 격리 경계를 분리함
- 실제 물리 메모리보다 큰 논리 주소 공간을 제공함
- 페이징은 외부 단편화를 줄이지만 내부 단편화가 남을 수 있음
- 세그멘테이션은 코드·데이터·스택별 보호와 공유 범위를 표현하며, 가변 크기 할당으로 외부 단편화가 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 분할·주소 변환 | 고정 크기 페이지, 페이지 번호와 오프셋 | 논리 단위 가변 크기, 세그먼트 번호와 변위 |
| 단편화 리스크 | 내부 단편화 가능 | 외부 단편화 가능 |
| 보호·공유 단위 | 고정 크기 페이지별 권한 설정 | 코드·데이터·스택 세그먼트별 권한 설정 |

> 요약: 페이징은 고정 크기 프레임 단위로 내부 단편화 위험을 가지고, 세그멘테이션은 논리 단위 보호 경계 대신 외부 단편화 위험을 가짐.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가상 주소 공간 | 프로세스별 주소 범위와 접근 권한을 제공함 |
| 페이지·세그먼트 테이블 | 논리 주소를 물리 위치에 매핑하고 권한을 저장함 |
| 물리 프레임 | 페이지 데이터를 적재하는 고정 크기 메모리 블록임 |
| 후면 저장소 | 메모리에 없는 페이지를 보관하는 보조기억장치 영역임 |

> 요약: 가상 주소는 변환 테이블을 거쳐 물리 프레임에 연결되고, 부재 페이지는 후면 저장소에서 적재함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 논리 주소 생성  | --> | 테이블 변환    | --> | 적재 여부 확인 | --> | 메모리 접근    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **논리 주소 생성**: CPU가 프로세스의 가상 주소를 생성함
2. **테이블 변환**: 페이지 테이블 또는 세그먼트 테이블로 물리 위치를 찾음
3. **적재 여부 확인**: 메모리에 없으면 페이지 폴트 예외를 발생시켜 후면 저장소에서 적재함
4. **메모리 접근**: 변환된 물리 주소로 실제 데이터를 읽거나 씀

## Ⅵ. 실무 사례

1. 메모리 집약 서버는 대형 페이지를 적용하고 TLB 실패율과 주요 페이지 폴트율을 확인함
2. 보호 영역 런타임은 세그먼트별 실행·쓰기 권한을 설정하고 권한 위반 수와 외부 단편화율을 확인함

## Ⅶ. 결론

- 가상 메모리는 보호·공유 단위와 주소 변환·단편화·페이지 폴트 비용을 기준으로 구조를 선택함
