## Ⅰ. 개요
- 소프트웨어 설계 시 반복적으로 발생하는 문제들에 대한 재사용 가능한 해결책임.
- GoF(Gang of Four) 패턴이 대표적이며, 목적에 따라 3가지 범주로 분류됨.
- 출제 의도: 패턴의 분류 체계 이해와 특정 상황에 적합한 패턴 선정 능력 확인.

## Ⅱ. 구성요소
- 패턴 분류 (GoF)
[Creational] | [Structural] | [Behavioral]

| 구성요소 | 설명 | 주요 패턴 |
| :--- | :--- | :--- |
| 생성 (Creational) | 객체의 생성 메커니즘을 캡슐화하여 유연성 제공 | Singleton, Factory, Builder |
| 구조 (Structural) | 클래스나 객체를 조합하여 더 큰 구조를 형성 | Adapter, Composite, Proxy |
| 행위 (Behavioral) | 객체 간의 상호작용과 책임 분산을 정의 | Observer, Strategy, State |
> 요약: 객체의 생성, 결합, 동작 방식을 표준화하여 개발 효율성을 높임.

## Ⅲ. 절차
- 디자인 패턴 적용 프로세스
[Problem Ident] -> [Pattern Match] -> [Structure Design] -> [Implementation]

1. 문제 파악: 중복 코드, 복잡한 조건문, 변경의 어려움 등 이슈를 식별함.
2. 패턴 선정: 문제 유형에 맞는 최적의 GoF 패턴을 선택함.
3. 아키텍처 설계: 클래스 다이어그램을 통해 패턴 구조를 설계에 반영함.
4. 구현: 인터페이스와 추상 클래스를 활용하여 실제 코드를 작성함.
> 요약: 검증된 설계 템플릿을 현업 문제에 대입하여 품질을 향상시킴.

## Ⅳ. 문제점
- 패턴에 끼워 맞추기식 설계(Over-engineering)로 인한 유지보수 비용 증가.

## Ⅴ. 개선방안
- 패턴의 의도를 정확히 이해하고 필요한 시점에만 최소한으로 적용.

## Ⅵ. 전망
- 클라우드 네이티브 및 마이크로서비스 환경을 위한 아키텍처 패턴과 통합.
- 생성형 AI 도구가 코드 맥락을 분석하여 최적의 디자인 패턴을 자동 추천.
