## Ⅰ. 개요
- 정의: 구글에서 주창한 소프트웨어 엔지니어링 관점으로 운영 문제를 해결하는 방법론.
- 출제 의도: 신뢰성과 혁신 속도의 균형을 맞추기 위한 SLO, 에러 버짓(Error Budget) 개념 이해 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ SLI ] (측정 지표: 가동률)
     |
  [ SLO ] (목표 수치: 99.9%)
     |
  [ Error Budget ] (허용된 실패: 0.1%) -> [ Innovation vs Stability ]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| SLI | 신뢰성 수준을 나타내는 구체적인 정량적 측정 지표 | 체온/혈압 |
| SLO | 비즈니스 가치를 고려해 정의한 서비스 수준 목표치 | 건강 유지 목표 |
| 에러 버짓 | 100% 신뢰성 대신 남겨둔 실패 허용 범위 (변경/혁신 자원) | 예비비 |
> 요약: 데이터 기반의 의사결정을 통해 운영을 자동화하고 안정성을 정량화함.

## Ⅲ. 절차
- ASCII 흐름도
  [지표 정의] -> [목표 설정] -> [상태 모니터링] -> [에러 버짓 소진 시 배포 중단]
- 4단계 설명
1. 서비스의 핵심 가치를 측정할 수 있는 SLI(응답시간 등)를 선정함.
2. 고객 만족을 위한 현실적인 SLO를 설정하고 이해관계자와 합의함.
3. 실시간 대시보드를 통해 서비스 상태와 남은 에러 버짓을 시각화함.
4. 버짓 소진 시 새로운 기능 배포를 멈추고 시스템 안정화 작업에 집중함.
> 요약: 장애를 피하는 것이 아니라 '관리 가능한 수준'으로 유지하는 전략임.

## Ⅳ. 문제점
- Toil(노동) 과다: 반복적이고 가치 없는 수동 작업이 늘어나 엔지니어의 번아웃 유발함.
- 비현실적 목표: 비즈니스 현실을 고려하지 않은 과도한 SLO 설정 시 개발 속도 저해함.

## Ⅴ. 개선방안
- 자동화 투자: 전체 업무의 50% 이상을 수동 작업 제거를 위한 자동화 개발에 할당함.
- Blameless Post-mortem: 장애 원인 분석 시 사람 대신 시스템 결함에 집중하여 개선 도출함.

## Ⅵ. 전망
- AIOps와 결합하여 대규모 인프라의 장애 패턴을 예측하고 자동 대응하는 지능형 SRE 확산됨.
- 핀옵스(FinOps)와 연계하여 신뢰성뿐만 아니라 비용 효율성까지 관리 지표로 통합 중임.
- 중앙 집중형 SRE 팀에서 각 개발 팀에 엔지니어가 내장되는 임베디드 SRE 모델로 진화될 것임.
