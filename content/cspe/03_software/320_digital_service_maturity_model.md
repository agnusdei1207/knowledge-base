# 📖 【암기용】 개념 완전 이해

> 목적: 디지털 서비스 성숙도 모형을 조직의 서비스 역량을 단계적으로 진단하는 도구로 이해하게 만든다.

## 한눈에
- **개요**: 디지털 서비스의 전략, 사용자 경험, 데이터, 기술, 운영, 거버넌스 수준을 단계로 진단하는 모형
- **왜 필요한가**: 서비스가 온라인에 있다고 디지털 역량을 갖춘 것은 아니다. 사용자 중심 설계, 데이터 기반 의사결정, 자동화 운영, 보안·접근성 통제가 함께 필요하다.
- **핵심 직관**: 운동 능력 평가처럼 현재 체력, 기술, 습관, 회복 능력을 측정하고 다음 훈련 단계를 정하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 많은 조직이 웹·앱을 만들었지만 부서별 단절, 수작업 처리, 데이터 사일로, 낮은 접근성, 장애 대응 미흡이 남아 있다. 성숙도 모형은 현재 수준과 개선 우선순위를 보이게 한다.
- **작동 원리**: 전략·프로세스·기술·데이터·조직·보안·운영 영역을 평가하고, 초기-관리-정의-측정-최적화 같은 단계로 구분한다. 각 단계는 증적과 지표로 판정한다.
- **비유**: 학교 성적표가 과목별 점수를 보여주듯 성숙도 모형은 UX, 데이터, 운영, 보안 같은 영역별 수준을 보여준다.
- **구체 예시**: Level 1은 수작업 민원 처리, Level 3은 표준 API와 통합 로그인, Level 5는 SLO·A/B Test·자동 복구·데이터 기반 정책 개선을 운영한다.
- **흔한 오해·주의점**: 성숙도는 높은 단계 선언이 목적이 아니다. 업무 영향과 투자 대비 효과를 보고 다음 분기 개선 항목을 정하는 도구다.

## 연결 개념
- 디지털 전환 - 업무·조직·기술 변화의 실행 틀
- IT 거버넌스 - 투자·위험·성과 관리
- SRE/DevOps - 운영 자동화와 관측성 성숙도 향상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 디지털 서비스 성숙도 모형의 평가 영역, 단계, 개선 방안을 답안으로 전개한다.
> 핵심: 성숙도 평가는 단계명 나열이 아니라 영역별 증적, 지표, 개선 로드맵으로 작성해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 디지털 서비스 성숙도 모형은 전략·UX·데이터·기술·운영·거버넌스 역량을 단계별로 진단하는 평가 체계다.
> 2. **가치**: 현재 수준을 수치와 증적으로 파악하고, 다음 단계 전환에 필요한 투자·조직·기술 과제를 도출한다.
> 3. **판단 포인트**: 성숙도 단계는 선언이 아니라 사용자 지표, 자동화율, 데이터 활용률, SLO, 보안·접근성 증적으로 판정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 성숙도 모형 구조 이해 확인 | 평가 영역과 단계 체계 | 단계명만 나열 |
| 디지털 전환 실행 판단 확인 | 현재 진단, 목표 단계, 로드맵 | 기술 도입 중심 답안 |
| 성과 지표 설계 확인 | 사용자 만족, 자동화율, SLO, 접근성 | 정성 표현만 제시 |

> 요약: 이 문제는 디지털 서비스 역량을 영역별 지표와 개선 로드맵으로 진단하는지를 본다.

---

## Ⅰ. 개요 및 필요성

- 개요: 디지털 서비스 역량 진단 도구
- 배경: 조직은 전략, 사용자 경험, 데이터, 기술, 운영, 거버넌스 수준을 같은 기준으로 비교하기 어려움
- 필요성: 성숙도 단계, Gap 분석, 개선 Roadmap으로 현재 수준과 다음 투자 우선순위를 결정해야 함

---

## Ⅱ. 구조 및 구성요소

```text
서비스 현황 -> 영역별 진단 -> 성숙도 단계 판정 -> 격차 분석 -> 개선 로드맵
                / 전략 / UX / 데이터 / 기술 / 운영 / 거버넌스
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 전략·거버넌스 | 목표, 예산, 책임 체계 평가 | KPI, 포트폴리오 |
| 사용자 경험 | 접근성, 여정, 만족도 평가 | WCAG, CSAT, NPS |
| 데이터·기술 | 데이터 활용, API, 자동화 평가 | API reuse, data quality |
| 운영·보안 | SLO, 장애 대응, 보안 통제 평가 | MTTR, audit log |

> 요약: 성숙도 모형은 전략부터 운영까지 서비스 역량을 영역별로 진단해 단계와 개선 과제를 도출한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
평가 기준 수립 -> 증적 수집 -> 점수 산정 -> 단계 판정 -> 개선 과제 실행
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 평가 영역과 단계 기준 정의 | 진단표, 배점 |
| 2 | 문서·시스템·운영 데이터 수집 | KPI, 로그, 설문 |
| 3 | 영역별 점수와 결함 산정 | 자동화율, SLO, 접근성 |
| 4 | 현재 단계와 목표 단계 비교 | gap analysis |
| 5 | 3~12개월 개선 로드맵 수립 | 과제, 예산, 책임자 |

> 요약: 성숙도 평가는 기준-증적-점수-단계-로드맵 순서로 실행된다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 프로젝트 단위 평가 | 서비스 포트폴리오 평가 | 다수 서비스 운영 조직 |
| 비용/성능 | 기능 개발 우선 | 격차 기반 투자 | 예산 제약과 개선 효과 |
| 운영/위험 | 장애 대응 후속 | SLO·보안·접근성 선제 관리 | 국민·고객 영향도 |

> 요약: 성숙도 모형은 단일 시스템 개선보다 조직 전체 디지털 서비스 역량을 높이는 의사결정 도구다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 형식 진단 | 증적 없는 자기평가 | 로그·문서·설문 교차 확인 | 증적 충족률 |
| 목표 과다 | 전 영역 동시 개선 | 영향도·비용 기준 우선순위 | 90일 과제 완료율 |
| 지표 왜곡 | 사용자 지표 누락 | CSAT, NPS, 접근성 포함 | 사용자 불만 건수 |

> 요약: 성숙도 진단은 증적 기반 평가와 우선순위 로드맵으로 실행 가능성을 확보한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 사용자 | CSAT 80점, 접근성 결함 0건 | 설문, 접근성 점검 |
| 운영 | SLO 99.9%, MTTR 30분 이하 | APM, 인시던트 기록 |
| 데이터/자동화 | API 재사용률 50%, 수작업 30% 감소 | API catalog, 업무 로그 |

> 요약: 성숙도 개선은 사용자, 운영, 데이터·자동화 지표가 함께 상승하는지로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 전략·UX·데이터·기술·운영·거버넌스 6개 영역 진단표를 만들고 서비스별 Level 1~5를 증적으로 판정
2. 상위 10개 사용자 여정에 대해 CSAT, NPS, p95 지연, 접근성, 민원 건수를 측정해 개선 우선순위 산정
3. 90일 단위 로드맵으로 SLO 대시보드, API 카탈로그, 자동화 배포, 데이터 품질 점검 과제를 실행

**결론 (2줄):**
- 기술사 판단: 단순 온라인화 단계 조직은 UX·접근성부터, 다수 서비스 운영 조직은 SLO·데이터 거버넌스·자동화 투자를 우선한다
- 향후 방향: 성숙도 모형은 AI 활용, 제로트러스트, 클라우드 FinOps, ESG 데이터까지 포함하는 서비스 거버넌스로 확장된다
