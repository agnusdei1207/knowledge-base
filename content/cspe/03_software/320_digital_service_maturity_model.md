# 📖 【암기용】 개념 완전 이해

> 목적: 디지털 서비스 성숙도 모형을 조직의 서비스 역량을 단계적으로 진단하는 도구로 이해하게 만든다.

## 한눈에
- **개요**: 디지털 서비스 성숙도 모형은 CMMI류 **성숙도 모형(Maturity Model)**을 디지털 서비스 영역에 적용한 것으로, 전략·UX·데이터·기술·운영·거버넌스 역량을 단계(Level)로 진단하는 평가 체계다.
- **왜 필요한가**: "온라인으로 서비스를 제공한다"와 "디지털 역량을 갖췄다"는 다르다. 조직마다 UX 수준, 자동화율, 데이터 활용도가 제각각이라 같은 기준 없이는 "우리가 지금 어디쯤인지, 다음에 뭘 투자해야 하는지"를 판단할 수 없다.
- **핵심 직관**: 체력측정과 같다 — 근력·지구력·유연성을 각각 측정하고 등급을 매긴 뒤 다음 훈련 계획을 짜듯, 성숙도 모형도 영역별 수준을 재고 다음 단계로 가는 로드맵을 짠다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 성숙도 모형(Maturity Model) | 상위개념 — 조직 역량을 정해진 단계로 진단하는 평가 틀(대표: SW공학의 CMMI) | 체력측정 등급표 |
| CMMI 5단계 | 초기(Initial)-관리(Managed)-정의(Defined)-정량관리(Quantitatively Managed)-최적화(Optimizing) — 이 모형의 원형이 된 단계 구분 | 초심자-숙련자-전문가-마스터-그랜드마스터 |
| Gap 분석 | 현재 단계와 목표 단계의 차이를 영역별로 계산하는 절차 | 현재 체력과 목표 체력의 격차 진단 |
| SLO(Service Level Objective) | 가용성·응답시간 등 서비스 품질 목표치(예: 99.9%) | 약속한 서비스 품질 기준선 |
| MTTR(Mean Time To Recovery) | 장애 발생부터 복구까지 걸리는 평균 시간 | 다쳤을 때 회복까지 걸리는 평균 시간 |
| CSAT(Customer Satisfaction) | 이용 후 만족도를 점수로 측정한 지표 | 만족도 설문 점수 |
| NPS(Net Promoter Score) | 추천 의향 기반 충성도 지표 = 추천고객 비율 - 비추천고객 비율 | 순수 추천 온도 |
| WCAG | 웹 접근성 국제 표준 지침 — 장애인·고령자도 이용 가능한지 판단 기준 | 웹판 장애인 편의시설 기준 |
| API 재사용률 | 신규 개발 시 기존 API를 재사용한 비율 — 기술 부채·중복개발 정도를 보여줌 | 부품 재사용률 |

## 깊이 이해

### 왜 "온라인화"와 "디지털 성숙도"는 다른가 (배경)
- 많은 조직이 웹·앱은 만들었지만 부서별 데이터가 분리돼 있고(사일로), 처리 과정 상당 부분이 여전히 수작업이며, 장애가 나도 대응 체계가 느리고, 접근성 기준을 충족하지 못하는 경우가 많다.
- "화면이 웹에 떠 있다"는 겉모습일 뿐, 실제 역량은 그 뒤의 데이터 흐름·자동화·운영 대응력에서 갈린다. 성숙도 모형은 이 뒷단 역량을 드러내기 위해 만들어졌다.

### CMMI형 5단계 구조 — 왜 이 순서인가
- 성숙도 모형 대부분은 SW공학의 CMMI(1~5단계) 구조를 차용한다. 1단계(초기)는 표준 없이 개인기에 의존, 2단계(관리)는 프로젝트 단위로 관리는 되지만 반복 가능하지 않음, 3단계(정의)는 조직 표준 프로세스 확립, 4단계(정량관리)는 지표로 프로세스를 통제, 5단계(최적화)는 지표 기반으로 지속 개선한다.
- 디지털 서비스 성숙도 모형도 같은 논리를 따른다: 낮은 단계는 "되긴 되는데 사람이 계속 붙어야 하는" 상태, 높은 단계는 "지표를 보며 스스로 개선되는" 상태다.

### SLO로 가용성 목표를 수치로 읽는 법 — 구체 수치 워크드 예제
- SLO 99.9% 가용성 목표를 잡았다면, 허용되는 월간 다운타임은 얼마일까. 30일 × 24시간 × 60분 = 43,200분이 한 달 전체 시간이다. 여기서 0.1%(=1-0.999)를 다운타임 허용치로 계산하면 43,200 × 0.001 ≈ 43.2분이다.
- 즉 "월 43분 이상 서비스가 멈추면 SLO 위반"이라는 뜻이다. 이렇게 퍼센트를 실제 분(分) 단위로 환산해야 담당자가 "이 정도는 괜찮다/위험하다"를 체감할 수 있다 — 성숙도 평가는 이런 식으로 추상적 목표를 실측 가능한 숫자로 바꾸는 과정이다.

### NPS로 충성도를 읽는 법 — 구체 수치 워크드 예제
- 이용자 100명에게 "이 서비스를 추천하겠습니까(0~10점)"를 물었더니 9~10점(추천고객, Promoter) 55명, 0~6점(비추천고객, Detractor) 15명, 7~8점(중립) 30명이 나왔다.
- NPS = 추천고객 비율 - 비추천고객 비율 = 55% - 15% = 40. NPS가 높을수록(이론상 -100~+100) 재이용·구전 가능성이 높은 서비스로 본다.
- CSAT(단순 만족도)와 다른 점: CSAT는 "지금 만족했는가"만 보지만 NPS는 "다음에도 남에게 권할 만큼 신뢰하는가"를 본다 — 그래서 성숙도 모형은 둘을 함께 쓴다.

### Gap 분석과 로드맵 — 판별 원리
- 판정 절차: ① 영역별(전략·UX·데이터·기술·운영·거버넌스) 현재 지표를 측정 → ② 각 지표를 단계별 기준값과 비교해 현재 Level 확정 → ③ 목표 Level과의 차이(Gap)를 영역별로 정리 → ④ Gap이 큰 영역부터 우선순위를 매겨 로드맵(보통 90일~12개월 단위)을 세운다.
- 여기서 핵심은 "Level 3이다"라고 선언하는 게 목적이 아니라, Gap이 어디에 있는지를 찾아 다음에 투자할 곳을 정하는 것이다.

### 흔한 오해
- 오해 1: 성숙도는 높을수록 무조건 좋다 → 실제로는 업무 영향과 투자 대비 효과를 보고 단계를 정한다. 모든 영역을 5단계로 올리는 것보다, 이용자 영향이 큰 영역부터 우선 개선하는 것이 맞다.
- 오해 2: 성숙도 평가는 정성적 인터뷰로 충분하다 → 증적(로그·지표·설문) 없는 자기평가는 형식 진단에 그친다. SLO·MTTR·NPS·API 재사용률처럼 측정 가능한 지표로 뒷받침해야 한다.

## 연결 개념
- 디지털 전환(Digital Transformation) — 성숙도 진단 이후 실행되는 업무·조직·기술 변화의 실행 틀
- IT 거버넌스 — 진단 결과를 투자·위험·성과 관리로 연결하는 상위 체계
- SRE/DevOps — 운영·자동화·관측성 영역의 성숙도를 실제로 끌어올리는 실행 방법론

## Ⅱ. 구조 및 구성요소

```text
서비스 현황 -> 영역별 진단 -> 성숙도 단계 판정 -> 격차 분석 -> 개선 로드맵
```

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 전략·UX·데이터·기술·운영·거버넌스 6개 영역 진단표를 만들고 서비스별 Level 1~5를 증적으로 판정
2. 상위 10개 사용자 여정에 대해 CSAT, NPS, p95 지연, 접근성, 민원 건수를 측정해 개선 우선순위 산정
3. 90일 단위 로드맵으로 SLO 대시보드, API 카탈로그, 자동화 배포, 데이터 품질 점검 과제를 실행

**결론 (2줄):**
- 기술사 판단: 단순 온라인화 단계 조직은 UX·접근성부터, 다수 서비스 운영 조직은 SLO·데이터 거버넌스·자동화 투자를 우선한다
