## 미리 알고가기

- CBAM은 아키텍처 대안을 비용과 편익 관점에서 비교하는 방법론임
- 품질 속성 개선 효과를 경제적 판단으로 연결한다
- 기술적으로 좋은 선택이 항상 비용 효율적인 선택은 아니다

## Ⅰ. 개요

- **정의/개념**: CBAM은 아키텍처 개선 대안이 성능과 가용성과 유지보수성 같은 품질 속성에 주는 편익과 그 구현 비용을 함께 평가해 투자 우선순위를 정하는 의사결정 방법론임
- **배경/필요성**: 아키텍처 대안은 대개 품질 향상과 비용 증가를 동시에 가져오므로, 설계 결정이 기술적 타당성뿐 아니라 투자 가치 측면에서도 검토되어야 함

## Ⅱ. 특징

- 품질 속성 논의를 비용과 편익의 의사결정 언어로 바꾼다
- 여러 개선 대안을 상대 비교하기 좋다
- 편익 산정이 주관적으로 흐를 위험이 있다
- ATAM 같은 구조적 위험 분석 결과와 결합할 때 효과가 크다

## Ⅲ. 종류 및 비교

| 판단 기준 | 기술 직관 중심 선택 | CBAM |
|:---|:---|:---|
| 결정 기준 | 경험과 감각 | 비용과 품질 편익 비교 |
| 장점 | 빠른 결정 | 투자 우선순위 명확화 |
| 한계 | 설명 책임 약함 | 산정 모델과 합의 필요 |
| 적합 환경 | 소규모 즉시 결정 | 대형 투자와 아키텍처 개선 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Architectural Strategy Option | 비교 대상이 되는 개선 대안으로 각각 다른 품질 효과와 비용 구조를 가진다 |
| Quality Benefit Estimation | 각 대안이 품질 속성에 미치는 기여도를 수치나 점수로 평가한다 |
| Cost Estimation | 구현과 운영과 전환 비용을 함께 계산해 실질 투자 부담을 드러낸다 |
| Priority Decision Matrix | 편익 대비 비용을 비교해 실행 순서와 보류 대안을 구분한다 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대안 정의      | --> | 편익 평가      | --> | 비용 산정      | --> | 우선순위 결정  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대안 정의**: 비교할 아키텍처 개선 방안을 정함
2. **편익 평가**: 품질 속성 개선 효과를 산정함
3. **비용 산정**: 개발과 운영과 이행 비용을 계산함
4. **우선순위 결정**: 편익 대비 비용으로 실행 순서를 정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 품질 편익을 수치화하는 기준이 불명확하면 결과가 회의 참가자 주관에 크게 흔들릴 수 있음
   - 해결방안: 공통 평가 척도를 운영하고 benefit estimation variance와 decision confidence score로 검증함
2. 문제: 초기 구현 비용만 보고 운영 복잡도와 장기 유지비를 빼면 잘못된 결론이 나올 수 있음
   - 해결방안: lifecycle cost를 포함하고 cost completeness ratio와 post-adoption cost delta로 검증함
3. 문제: CBAM 결과를 실제 투자와 연결하지 않으면 분석만 하고 개선은 지연될 수 있음
   - 해결방안: 포트폴리오 계획과 연계하고 funding alignment rate와 action execution ratio로 검증함

## Ⅶ. 적용 사례

- 코어 플랫폼 개선안 비교에서는 CBAM을 사용하고 확인 지표는 decision confidence score와 funding alignment rate임
- 클라우드 전환 투자 검토에서는 lifecycle cost를 반영하고 확인 지표는 cost completeness ratio와 post-adoption cost delta임
- 아키텍처 위원회에서는 품질 편익 점수를 통일하고 확인 지표는 benefit estimation variance와 action execution ratio임

## Ⅷ. 결론

CBAM의 핵심은 기술 대안을 숫자로 포장하는 데 있지 않고 품질 향상과 비용 부담을 같은 테이블 위에 올려 투자 결정을 더 투명하게 만드는 데 있음.
