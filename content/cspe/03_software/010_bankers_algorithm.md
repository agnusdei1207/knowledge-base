## Ⅰ. 개요
- 정의: 은행가 알고리즘은 자원 요청을 가상 할당한 뒤 안전 순서가 존재할 때만 실제 할당하는 교착상태 회피 기법임
- 배경: 데드락 예방의 자원 낭비를 줄이고, 발생 후 복구의 위험을 피하기 위해 고안됨
- 출제 의도: 가용 자원, 최대 요구, 현재 할당량 기반의 안전 순서(Safe Sequence) 산출 능력 검증

## Ⅱ. 구성요소
```
[ Data Structures ]
- Available: 가용 자원 벡터
- Max: 최대 요구 행렬
- Allocation: 현재 할당 행렬
- Need: 추가 요구 행렬 (Max - Allocation)
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 안전 상태 | 데드락 없이 모든 프로세스를 완료할 수 있는 순서 존재 | 안전 순서 존재 |
| Need 행렬 | 각 프로세스가 작업을 끝내기 위해 더 필요한 자원 | Max - Allocation |
| Work 벡터 | 검사 과정에서 자원 반납을 가정한 임시 가용 자원 | 가정된 가용량 |
> 요약: 요청 승인 후에도 완료 가능한 프로세스 순서가 남는지 검사함.

## Ⅲ. 절차
```
[Request] -> [Need Check] -> [Available Check] -> [Safety Test] -> [Assign/Reject]
```
1. 특정 프로세스의 자원 요청이 자신의 최대 요구량(Need) 이하인지 확인
2. 요청량이 현재 가용 자원(Available) 이하인지 확인해 검사 진행 또는 대기를 결정함
3. 요청을 승인했다고 가정하고 시스템이 '안전 상태'로 남는지 Safety 알고리즘 수행
4. 안전 순서(Safe Sequence)가 존재하면 자원을 할당하고, 없으면 요청 거절 및 대기
> 요약: 요청을 가상 할당한 상태에서 모든 프로세스가 완료되는 안전 순서를 찾으면 실제 자원을 할당함.

## Ⅳ. 문제점
- 원인: 프로세스가 사용할 최대 자원량을 미리 정확히 알기 어렵고 동적 변화에 취약함
- 원인: 자원 할당 시마다 알고리즘을 수행해야 하므로 성능 저하(Overhead) 유발

## Ⅴ. 개선방안
- (단기) 자원 그룹화 및 계층적 할당을 통한 검사 대상 수 축소로 오버헤드 경감
- (중기) 가상화 환경에서 하이퍼바이저 수준의 자원 가용성 모니터링 시스템과 연동
- (장기) 정적 분석 도구를 활용하여 코드 수준에서 최대 자원 소요량을 사전에 추정

## Ⅵ. 전망
- 클라우드 자원 오케스트레이션에서는 쿼터와 예약량을 비교해 과할당 위험을 통제함
- 한정된 엣지 디바이스에서는 최대 요구량 추정이 가능한 자원에 한해 회피 로직을 단순화해 적용함

## 작성 근거(검토용)

- 은행가 알고리즘은 예시보다 Available, Allocation, Need, Work로 안전 순서가 존재하는지 계산하는 절차가 중심임
- 클라우드 적용은 `철학` 같은 표현을 빼고 쿼터, 예약량, 과할당 위험 통제라는 대응 관계로 제한함
