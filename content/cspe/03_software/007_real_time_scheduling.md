## Ⅰ. 개요
- **정의**: 태스크의 데드라인 내 완료를 보장하는 스케줄링 기법
- **배경/필요성**: 항공·의료·제조 등 데드라인 위반이 치명적인 시스템에서 시간 보장이 필요함
- **비유**: 응급실 환자를 도착 순서가 아닌 긴급도·치료 마감 시간 순으로 처리하는 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 경성/연성 RT 구분과 알고리즘 | RM vs EDF 스케줄러빌리티 조건 | 경성 RT의 데드라인 보장 조건 수식 명시 |

> 요약: 데드라인 충족을 최우선 목표로 태스크 실행 순서를 결정하는 스케줄링임

## Ⅱ. 구성요소
```text
RT Task Set --> Admission Control --> Scheduler (RM/EDF) --> Dispatch
                 (Feasibility)          (Priority)          (CPU)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 경성 RT | 데드라인 위반 시 시스템 실패로 간주 | 수술 마감 시간 |
| 연성 RT | 데드라인 위반 시 품질 저하만 발생 | 영상 프레임 드롭 |
| RM(Rate Monotonic) | 주기가 짧은 태스크에 높은 고정 우선순위 부여 | 자주 오는 환자 우선 |
| EDF(Earliest Deadline First) | 데드라인이 가장 가까운 태스크를 우선 실행 | 마감 임박 업무 우선 |

> 요약: 경성/연성 분류와 RM/EDF 알고리즘이 핵심 구성임

## Ⅲ. 절차
```text
태스크 등록 --> 스케줄러빌리티 검증 --> 우선순위 배정 --> 디스패치/선점
```
- 1단계: RT 태스크의 주기(T), 실행시간(C), 데드라인(D) 파라미터 등록
- 2단계: 이용률 합($\sum C_i/T_i \le 1$) 기반 스케줄러빌리티 검증 수행
- 3단계: RM은 주기 역순, EDF는 절대 데드라인 순으로 우선순위 배정
- 4단계: 높은 우선순위 태스크 도착 시 현재 태스크를 선점하여 디스패치

> 요약: 등록-검증-배정-선점 4단계로 데드라인 준수를 보장함

## Ⅳ. 문제점
- 우선순위 역전: 저우선 태스크가 공유 자원 점유 — 고우선 태스크가 대기하게 됨
- RM 이용률 한계: 이용률 상한이 $n(2^{1/n}-1)$ — 태스크 수 증가 시 약 69%로 수렴하여 CPU 낭비
- 과부하 시 연쇄 실패: EDF 과부하 상태 — 다수 태스크가 동시에 데드라인 위반하는 도미노 현상

> 요약: 우선순위 역전, 이용률 한계, 과부하 연쇄 실패가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 우선순위 상속(Priority Inheritance) 프로토콜로 우선순위 역전 해소
2. 중기: EDF 채택으로 이론적 이용률 100%까지 활용하여 CPU 낭비 절감
3. 장기: 서버 기반 스케줄링(CBS 등) 도입으로 과부하 시에도 태스크 격리 및 영향 차단

> 요약: 우선순위 상속, EDF 전환, 서버 기반 격리로 실시간성을 강화함

## Ⅵ. 전망
- 발전 방향: 자율주행·스마트팩토리 확산으로 혼합 임계도(Mixed-Criticality) 스케줄링 수요 증가
- 기술사적 판단: 단일 RT 정책보다 임계도별 계층 분리 스케줄링이 주류가 될 전망
- 기술사 제언: 안전 등급(SIL/ASIL)에 맞는 RT 스케줄링 정책 선정 기준 가이드 수립이 필요
