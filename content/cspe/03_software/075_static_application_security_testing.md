## 미리 알고가기

- SAST는 애플리케이션 실행 없이 소스 코드나 바이트코드를 분석하는 보안 검사임
- 취약한 API 사용과 입력 검증 누락과 하드코딩 비밀 탐지에 강함
- 빠른 조기 탐지가 장점이지만 오탐 관리가 중요함

## Ⅰ. 개요

- **정의/개념**: 정적 애플리케이션 보안 테스트 SAST는 소스 코드와 바이트코드와 설정 파일을 실행 없이 분석해 보안 취약 패턴과 위험한 코딩 관행을 조기에 탐지하는 보안 검증 기법임
- **배경/필요성**: 배포 후 보안 결함 수정은 비용이 크고 영향 범위도 넓으므로, 개발 단계에서 취약점을 빠르게 식별해 수정 비용을 줄일 필요가 있음

## Ⅱ. 특징

- 개발 초기와 CI 단계에서 빠르게 적용할 수 있음
- 코드 수준 취약점과 비밀 노출과 정책 위반 탐지에 효과적임
- 실행 흐름과 실제 악용 가능성 판단에는 한계가 있음
- 오탐이 많으면 개발자 수용성이 급격히 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | SAST | DAST |
|:---|:---|:---|
| 분석 시점 | 실행 전 코드 분석 | 실행 중 동작 분석 |
| 장점 | 조기 발견과 빠른 피드백 | 실제 동작 취약점 확인 |
| 한계 | 오탐과 런타임 맥락 한계 | 늦은 발견과 환경 필요 |
| 적합 환경 | 개발·CI 단계 | 통합·운영 전 단계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Rule Engine | 취약 패턴과 금지 API와 정책 기준을 정의해 코드 분석 기준을 만든다 |
| Code Scanner | 저장소와 빌드 산출물을 분석해 위험 위치를 식별함 |
| Triage Workflow | 경고를 실제 위험과 오탐으로 구분해 개발 흐름에 맞게 정리함 |
| Remediation Feedback | 수정 결과를 추적해 반복 취약점과 미조치 항목을 관리함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드 변경      | --> | 정적 스캔      | --> | 경고 분류      | --> | 수정/정책 보강 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드 변경**: 커밋이나 병합 요청이 분석 대상이 됨
2. **정적 스캔**: 도구가 취약 패턴과 정책 위반을 찾음
3. **경고 분류**: 실제 위험과 오탐과 예외를 구분함
4. **수정 및 정책 보강**: 취약점 수정과 규칙 개선을 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 경고 수가 너무 많거나 오탐률이 높으면 개발자가 결과를 무시하게 될 수 있음
   - 해결방안: 규칙 튜닝과 위험도 우선순위를 적용하고 alert precision과 developer acknowledgement rate로 검증함
2. 문제: 정적 분석만으로는 실제 런타임 악용 가능성과 취약점 도달성을 충분히 판단하기 어려울 수 있음
   - 해결방안: DAST와 코드 리뷰를 병행하고 exploitability confirmation rate와 defect escape rate로 검증함
3. 문제: 취약점 발견 후 수정 SLA가 없으면 결과가 쌓이기만 하고 보안 수준은 개선되지 않을 수 있음
   - 해결방안: remediation SLA를 운영하고 open vulnerability age와 remediation lead time으로 검증함

## Ⅶ. 적용 사례

- 금융 개발 파이프라인에서는 SAST를 적용하고 확인 지표는 alert precision과 remediation lead time임
- 대규모 레거시 코드베이스에서는 규칙 우선순위를 운영하고 확인 지표는 developer acknowledgement rate와 open vulnerability age임
- 보안 품질 리뷰에서는 DAST와 병행 검증을 수행하고 확인 지표는 exploitability confirmation rate와 defect escape rate임

## Ⅷ. 결론

SAST의 가치는 경고를 많이 만드는 데 있지 않고 개발 흐름 안에서 수정 가능한 시점에 의미 있는 취약점을 조기에 드러내는 데 있음.
