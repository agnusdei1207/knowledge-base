## Ⅰ. 개요
- **정의**: 프로그램의 실행 시간·메모리 사용량을 줄이도록 중간 코드 또는 목적 코드를 변환하는 기법
- **배경/필요성**: 동일 기능을 수행하면서 자원 소비를 낮추면 처리량 증가와 응답 시간 단축이 가능하므로 컴파일러 후단에서 체계적 최적화가 필요함
- **비유**: 같은 목적지로 가되 신호등·우회로를 미리 파악해 최단 경로로 달리는 내비게이션과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 최적화 분류와 기법 이해 | 지역/전역/기계종속 최적화 구분 | 최적화가 프로그램 의미를 변경하지 않아야 한다는 제약 명시 |

> 요약: 프로그램 의미를 보존하면서 실행 효율을 높이는 코드 변환 기법임

## Ⅱ. 구성요소
```text
Source Code
    |
    v
+------------------+
| Front-End        |
+------------------+
    |
    v
+------------------+     +------------------+
| Local Opt.       | --> | Global Opt.      |
+------------------+     +------------------+
    |
    v
+------------------+
| Machine-Dep Opt. |
+------------------+
    |
    v
Optimized Code
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 지역 최적화 | 기본 블록 내 상수 폴딩·강도 감소·공통 부분식 제거 수행 | 한 문단 내 중복 문장 제거 |
| 전역 최적화 | 제어 흐름 그래프 전체에서 루프 불변 코드 이동·죽은 코드 제거 수행 | 전체 원고에서 불필요한 단락 삭제 |
| 기계 종속 최적화 | 레지스터 할당·명령어 스케줄링 등 타깃 CPU 특성 반영 | 특정 도로 폭에 맞춰 차선 배치 조정 |

> 요약: 범위(지역-전역)와 타깃 의존성에 따라 최적화 기법이 계층적으로 적용됨

## Ⅲ. 절차
```text
IR 입력 --> 데이터 흐름 분석 --> 변환 적용 --> 결과 검증 --> 최적 IR 출력
```
- 1단계: 중간 표현(IR)을 입력받아 기본 블록·제어 흐름 그래프 구성
- 2단계: 도달 정의·활성 변수 등 데이터 흐름 분석 수행
- 3단계: 분석 결과에 따라 상수 전파·루프 불변 코드 이동 등 변환 적용
- 4단계: 변환 후 프로그램 의미 보존 여부를 검증하고 최적 IR 출력

> 요약: 분석-변환-검증의 반복을 통해 의미 보존 하에 효율을 개선함

## Ⅳ. 문제점
- 컴파일 시간 증가: 정밀 분석·반복 변환으로 빌드 시간이 길어짐 — 개발 생산성 저하 유발
- 디버깅 난이도 상승: 코드 재배치·제거로 소스-바이너리 매핑이 깨짐 — 디버거 추적 곤란
- 과도 최적화 부작용: 컴파일러가 정의되지 않은 동작을 이용해 예상치 못한 코드 제거 발생 — 프로그램 정확성 훼손 가능

> 요약: 빌드 시간·디버깅·정확성 측면에서 최적화 수준 조절이 필요함

## Ⅴ. 개선방안
1. 단기: 최적화 레벨(`-O0`~`-O3`) 단계별 적용으로 빌드 시간과 성능 간 균형 확보
2. 중기: DWARF 디버그 정보 보강 및 소스 맵 유지로 최적화된 바이너리에서도 디버깅 지원
3. 장기: 형식 검증(Translation Validation) 도입으로 변환 전후 의미 동치성 자동 증명

> 요약: 레벨 조절·디버그 정보·형식 검증으로 최적화 부작용을 체계적으로 완화함

## Ⅵ. 전망
- 발전 방향: MLIR 등 다계층 IR 기반 최적화 프레임워크로 도메인별 맞춤 최적화 확대
- 기술사적 판단: AI 워크로드 증가로 연산 그래프 수준 최적화의 중요성이 높아지고 있음
- 기술사 제언: 전통 컴파일러 최적화와 런타임 프로파일 기반 최적화를 병행하는 하이브리드 전략 수립이 필요함
