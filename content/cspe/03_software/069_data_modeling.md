## Ⅰ. 개요
- 현실 세계의 비즈니스 프로세스를 추상화하여 논리적/물리적 데이터 구조로 설계하는 과정임.
- ERD(Entity-Relationship Diagram)는 개체, 속성, 관계를 시각적으로 표현하는 표준 도구임.
- 출제 의도: 요구사항을 구조화된 데이터 모델로 변환하는 설계 역량 평가.

## Ⅱ. 구성요소
- ER 모델 기본 기호
[Entity: Box] --- <Relationship: Diamond> --- [Entity: Box]
       | (Attribute: Oval)

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Entity | 독립적으로 존재하는 관리 대상 (강한/약한 개체) | 명사 (회원, 상품) |
| Relationship | 개체 간의 논리적 연결 (1:1, 1:N, N:M) | 동사 (주문하다) |
| Attribute | 개체가 가진 성질이나 상태 (식별자, 일반) | 형용사 (이름, 가격) |
> 요약: 개체와 관계를 통해 비즈니스 룰을 도식화함.

## Ⅲ. 절차
- 데이터 모델링 3단계
[Conceptual] -> [Logical] -> [Physical]

1. 개념적 모델링: 핵심 엔티티 도출 및 ERD 작성 (DBMS 독립적).
2. 논리적 모델링: 정규화 수행, 상세 속성 정의, 매핑 룰 적용.
3. 물리적 모델링: 성능 고려하여 인덱스, 파티션, 테이블 스페이스 설계.
4. 검증: 업무 규칙 준수 여부 및 모델의 완전성 검토 수행함.
> 요약: 추상화에서 구체화로 이행하며 실제 구현 가능한 구조 확정함.

## Ⅳ. 문제점
- 복잡한 N:M 관계의 직접 구현 불가 및 속성 누락 시 모델의 결함 발생.

## Ⅴ. 개선방안
- 관계 해소 엔티티(Intersection Entity) 도입 및 도메인 전문가와의 지속적 리뷰.

## Ⅵ. 전망
- AI 기반 자동 모델링 및 SQL 역공학 기술을 통한 설계 생산성 향상 가시화.
- 데이터 거버넌스와 결합된 표준화 모델링 관리(MDM) 체계 강화.
