# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 스케줄링 알고리즘의 우선순위 편향으로 인해 특정 프로세스가 자원을 무한히 할당받지 못하는 상태(기아)와, 대기 시간에 비례해 우선순위를 높여 이를 해결하는 기법(에이징).
- **왜 필요한가**: SJF(Shortest Job First)나 우선순위 스케줄링에서는 우선순위가 낮은 프로세스가 평생 CPU를 얻지 못할 수 있다. 시스템의 공정성(Fairness)을 보장하기 위해 에이징 메커니즘이 필수적이다.
- **핵심 직관**: 식당에서 대기 줄이 긴데, VIP 손님이 올 때마다 일반 손님이 계속 뒤로 밀리는 것이 '기아'라면, 기다린 시간만큼 일반 손님에게도 VIP 쿠폰을 주어 결국 들어가게 해주는 것이 '에이징'이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **기아 (Starvation)** | 자원 할당 과정에서 계속 후순위로 밀려 무한 대기하는 현상 | "새치기를 영원히 당하는 상태" |
| **에이징 (Aging)** | 시스템에 머문 대기 시간에 비례하여 프로세스의 우선순위를 점진적으로 상향시키는 기법 | "오래 기다린 손님에게 우선 입장권 부여" |
| **교착상태 (Deadlock)** | 프로세스들이 서로의 자원을 요구하며 환형 대기 상태에 빠져 시스템 전체가 멈추는 현상 | "두 차가 골목에서 마주쳐 서로 비키라고 버티는 상태" |

## 깊이 이해
- **배경·문제의식**: 효율성을 극대화하기 위해 수행 시간이 짧은 작업을 우대(SJF, SRTF)하거나, 중요도가 높은 작업을 우대(Priority Scheduling)하면, 필연적으로 하위 작업의 대기 시간이 발산하는 불공정성(Unfairness) 문제가 발생한다.
- **작동 원리**: 
  - **기아 발생**: 우선순위 $P=5$인 작업이 대기 중인데, $P=1, 2, 3$ 인 작업이 계속 큐에 유입되면 $P=5$ 작업은 자원을 얻지 못한다.
  - **에이징 적용**: 매 타이머 인터럽트(또는 특정 주기)마다 대기 중인 작업의 우선순위 $P$를 $P - \alpha$ (숫자가 작을수록 우선순위 높음) 형태로 조정한다. 결국 $P$가 충분히 작아져 자원을 획득하게 된다.
- **구체 예시**: HRRN (Highest Response Ratio Next) 스케줄링. 우선순위 판정식을 $ (대기 시간 + 서비스 시간) / 서비스 시간 $ 으로 설정하여, 서비스 시간이 길더라도 대기 시간이 길어지면 비율이 1보다 훨씬 커져 결국 스케줄링되도록 설계한 것이 대표적인 에이징 기법이다.
- **흔한 오해·주의점**: 기아와 교착상태를 자주 혼동한다. 교착상태는 자원의 상호 점유로 인해 '아무도' 진행하지 못하는 상태지만, 기아는 시스템은 다른 프로세스를 잘 처리하고 있는데 '특정 프로세스만' 진행하지 못하는 상태다.

## 연결 개념
- **우선순위 스케줄링, SJF, SRTF**: 기아를 유발하는 대표적인 스케줄링 알고리즘
- **HRRN, MLFQ**: 기아를 방지(에이징)하도록 설계된 스케줄링 알고리즘

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 기아는 우선순위 편향으로 인한 특정 프로세스의 무한 대기 현상이며, 에이징은 대기 시간에 비례해 우선순위를 보정하는 동적 해결 기법이다.
> 2. **가치**: 성능(효율성) 중심의 스케줄링에서 훼손될 수 있는 공정성(Fairness)을 보장하고 작업의 응답 시간을 유계(Bounded) 범위 내로 통제한다.
> 3. **판단 포인트**: 기아와 교착상태의 발생 조건과 해결 접근법(스케줄링 보정 vs 자원 통제)을 명확히 구분하여 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기아의 원인과 해결 기법의 메커니즘 이해 | 기아 발생 알고리즘(SJF, Priority)과 에이징(HRRN) 수식 기반 설명 | 기아와 교착상태의 개념 혼용 및 원인 오진 |
| 스케줄링 공정성과 효율성의 트레이드오프 파악 | 대기 시간 기반 동적 우선순위 조정 원리 | 에이징 적용을 성능 향상으로 단순 단정 |

> 요약: 스케줄링 불공정성으로 인한 기아 현상을 명확히 정의하고, 에이징을 통한 동적 우선순위 보정 원리를 수식과 구조로 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 기아 현상은 자원 할당 우선순위가 낮은 프로세스가 무한히 대기하는 상태이며, 에이징은 이를 막기 위해 대기 시간에 비례하여 우선순위를 상향하는 기법
- 배경: SJF, SRTF, 정적 우선순위 스케줄링 등 효율성 중심 알고리즘은 필연적으로 하위 작업의 기아를 유발
- 필요성: 시스템 내 모든 프로세스의 최대 응답 시간(SLA)을 보장하고, 스케줄링 공정성(Fairness)을 확보하기 위해 동적 보정 필수

---

## Ⅱ. 구조 및 구성요소

```text
[새 프로세스 유입] -> Ready Queue (우선순위 정렬) -> 스케줄러 -> CPU 할당
                        |                           |
                        +-> [대기 시간 임계치 초과] -> [에이징: 우선순위 + \alpha 상향]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Ready Queue | 프로세스가 CPU 할당을 대기하는 큐 | 우선순위 기반 정렬 |
| 스케줄러 | 큐의 최상단 프로세스를 선택하여 CPU 할당 | SJF, Priority 등 편향 알고리즘 적용 시 기아 유발 |
| 에이징 모니터 | 프로세스의 큐 체류 시간을 주기적으로 계산 | 임계치 초과 시 동적 우선순위 재계산(상향) 수행 |

> 요약: 스케줄러가 편향된 자원 할당을 할 때, 에이징 모니터가 대기 시간을 추적하여 큐 내의 우선순위를 동적으로 재조정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
프로세스 큐 진입 -> 스케줄링 판정 대기 -> 타이머 인터럽트(주기적) -> 대기 시간 기반 우선순위 재계산 -> 자원 할당
```

- 1단계 [큐 진입 및 초기 우선순위 부여]: 프로세스가 정적 우선순위(또는 예상 실행 시간)를 부여받고 Ready Queue 진입
- 2단계 [우선순위 기반 대기]: 자신보다 높은 우선순위 프로세스가 계속 유입되어 자원 할당이 지연됨(기아 발생)
- 3단계 [에이징 기반 우선순위 상향]: 타이머 인터럽트 시점마다 `New Priority = Base Priority + (Wait Time * \alpha)` 계산
- 4단계 [최종 자원 할당]: 상향된 우선순위가 큐 최상단에 도달하여 CPU를 할당받고 실행 완료

> 요약: 프로세스의 대기 시간이 길어질수록 에이징 수식에 의해 동적 우선순위가 역전되어 최종적으로 자원을 보장받는다.

---

## Ⅳ. 특징
- 동적 보정: 프로세스 속성(정적)뿐 아니라 상태(대기 시간)를 스케줄링 파라미터로 통합
- 공정성 회복: 극단적인 효율성 추구로 인한 하위 작업의 영구 배제를 차단하고 응답 시간의 상한을 보장
- 연산 오버헤드: 매 주기마다 큐 내 모든 프로세스의 대기 시간을 측정하고 정렬을 갱신해야 하므로 CPU 사이클 소모

> 요약: 효율성과 공정성의 균형을 맞추는 강력한 동적 통제 기법이나, 우선순위 재계산 및 정렬에 따른 컨텍스트 스위칭 오버헤드가 발생한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기아 현상 (Starvation) | 교착상태 (Deadlock) | 선택/판단 기준 |
|:---|:---|:---|:---|
| 발생 원인 | 스케줄러의 우선순위 편향 | 자원의 상호 점유 및 환형 대기 | 문제의 근본 원인이 스케줄링인지 자원 통제인지 판단 |
| 진행 상태 | 일부 하위 작업만 대기, 시스템은 정상 진행 | 연관된 모든 프로세스가 진행 정지 | 시스템 전체의 처리량(Throughput) 저하 여부 |
| 해결 접근 | 에이징 (Aging), HRRN 적용, 라운드 로빈 | 예방, 회피(Banker's), 탐지 및 복구 | 스케줄링 알고리즘 교체 vs 자원 할당 그래프 제어 |

> 요약: 기아는 큐 정책의 불공정성 문제이므로 에이징으로 해결하고, 교착상태는 자원 할당 구조의 문제이므로 회피 및 복구 기법으로 접근해야 강건한 시스템이 된다.

**리스크·대응:**
- 연산 오버헤드 증가: 매 클럭 에이징 연산 시 성능 저하 → 다단계 피드백 큐(MLFQ)처럼 특정 주기나 큐 이동 시에만 일괄 승급 적용 (지표: 스케줄러 오버헤드 비율)
- 역차별 발생: 에이징 임계치($\alpha$)가 너무 크면 중요도가 높은 실시간 작업이 밀림 → 실시간 큐와 일반 큐를 분리하여 에이징 적용 차등화 (지표: 실시간 프로세스 데드라인 준수율)

**도입 후 점검 지표:**
- 공정성: 최대 응답 시간(Max Response Time) SLA 달성률 — 프로세스별 대기 시간 분포 측정
- 성능: 스케줄링 오버헤드 비율 < 전체 CPU 주기의 1~2% 이내 유지 — 커널 프로파일링

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. MLFQ 스케줄링 적용: 하위 큐에서 일정 시간(예: 100ms) 이상 대기한 프로세스를 상위 큐로 일괄 승급(Priority Boost)시켜 기아 원천 차단
2. HRRN (Highest Response Ratio Next) 도입: 배치 시스템에서 응답률 $ (Wait+Service)/Service $ 을 기준으로 스케줄링하여 수행 시간과 대기 시간을 동시 고려
3. CFS (Completely Fair Scheduler) 사용: 리눅스 커널에서 프로세스별 가상 런타임(vruntime)을 추적하여, 가장 적게 실행된 작업에 우선권을 부여하는 구조적 공정성 확보

**결론 (2줄):**
- 기술사 판단: 기아 현상은 성능 최적화의 필연적 부작용이므로, MLFQ나 CFS와 같은 구조적 에이징 메커니즘을 OS 스케줄러에 기본 탑재해야 한다.
- 향후 방향: 최근 클라우드 환경에서는 컨테이너별 자원 쿼터(Quota)와 결합하여, 단순 대기 시간이 아닌 SLA 및 비용 기반의 다차원 에이징 기법으로 발전해야 한다.
