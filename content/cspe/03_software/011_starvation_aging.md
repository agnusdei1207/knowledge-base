## 미리 알고가기

- 기아: 특정 작업이 계속 선택에서 밀려 실행 기회를 얻지 못하는 상태임
- 에이징: 대기시간이 늘어날수록 작업 우선순위를 단계적으로 높이는 기법임
- 우선순위 상향 주기: 대기시간을 확인하고 우선순위를 변경하는 시간 간격임
- 준비 큐: 실행을 기다리며 스케줄러의 선택 대상이 되는 작업 집합임

## 작성 근거(검토용)

- 기아 원인을 고정 우선순위와 연속 고우선 작업 도착으로, 대응을 대기시간 보정으로 설명함
- 고정 우선순위와 에이징을 선택 기준·리스크·설정값으로 비교함
- 운영체제와 작업 큐 사례는 최대 대기시간과 상향 횟수를 직접 확인하도록 구성함

## Ⅰ. 개요
- **정의/개념**: 기아는 특정 작업이 우선순위 경쟁에서 계속 밀려 실행되지 않는 상태이고, 에이징은 대기시간에 따라 우선순위를 높여 실행 기회를 제공하는 기법임
- **배경/필요성**: 우선순위 스케줄링에서 낮은 우선순위 작업의 장기 대기를 제한하기 위해 대기시간 보정 기준이 필요함

## Ⅱ. 특징

- 고우선순위 작업이 계속 도착하면 낮은 우선순위 작업의 대기시간이 증가함
- 에이징은 검사 주기마다 누적 대기시간을 반영해 우선순위를 보정함
- 보정된 우선순위가 다른 대기 작업보다 높아지면 스케줄러가 해당 작업을 먼저 선택함
- 상향 폭이 크면 긴급 작업 순서가 바뀔 수 있어 주기와 상한을 함께 설정함

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정 우선순위 | 에이징 적용 우선순위 |
|:---|:---|:---|
| 선택 기준 | 사전 우선순위만 사용, 대기 중에도 값 불변 | 사전 우선순위에 누적 대기시간을 반영해 주기마다 재산정 |
| 리스크 | 고우선 작업이 계속 도착하면 기아 지속 | 상향 폭이 크면 긴급 작업의 실행 순서가 밀릴 수 있음 |
| 설정값 | 우선순위 등급만 존재 | 검사 주기·상향 폭·상한 |

> 요약: 고정 우선순위는 대기 중 값이 바뀌지 않고, 에이징은 누적 대기시간을 우선순위에 반영함.

## Ⅳ. 구성요소 및 구조
```
[ 준비 큐 ] P1(고) P2(고) ... P100(저)
                                    |
                                    v  (장기 대기)
                          [ 에이징 적용 -> 우선순위 상향 ]
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 기아 현상 | 높은 우선순위 작업에 밀려 특정 작업 실행이 계속 지연됨 | 대기 시간 |
| 에이징 | 대기 시간이 경과할수록 우선순위 값을 점진적으로 증가시킴 | 우선순위 증가율 |
| 우선순위 | 스케줄러가 작업을 선택하는 기준값 | 실행 대상 선택 |
> 요약: 에이징은 대기 시간을 우선순위에 반영해 장기 대기를 줄임.

## Ⅴ. 원리 및 절차 흐름도
```
[대기] -> [시간 확인] -> [우선순위 상향] -> [스케줄링]
```
1. **대기시간 누적**: 선택되지 않은 작업의 준비 큐 대기시간을 갱신함
2. **상향 시점 판정**: 누적 대기시간이 검사 주기 기준을 넘었는지 확인함
3. **우선순위 보정**: 정한 폭과 상한 안에서 작업 우선순위를 높임
4. **실행 대상 선택**: 보정된 우선순위로 준비 큐를 다시 평가함
> 요약: 대기 시간이 길수록 선택 가능성이 커지도록 우선순위를 보정함.

## Ⅵ. 실무 사례

1. 운영체제 준비 큐는 에이징 주기를 설정하고 우선순위별 최대 대기시간과 상향 횟수를 확인함
2. 배치 작업 큐는 장기 대기 작업의 우선순위를 보정하고 기아 작업 수와 작업 완료시간을 확인함

## Ⅶ. 결론

- 에이징은 누적 대기시간·상향 주기·상한을 기준으로 우선순위를 보정해 기아를 통제함
