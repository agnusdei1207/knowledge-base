## Ⅰ. 개요
- **정의**: 신규 모델을 소량 트래픽에 먼저 노출하여 검증 후 점진적으로 확대하는 배포 전략임
- **배경/필요성**: 전체 트래픽을 한번에 전환하면 모델 결함 발생 시 피해 범위가 전체 사용자로 확산됨
- **비유**: 탄광 카나리아처럼 소수에게 먼저 적용해 위험을 조기 감지하는 방식임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 안전한 모델 배포 전략 이해 | 트래픽 분할 비율·승격 기준 | Shadow Deployment(258)와 혼동 주의 |

> 요약: 소량 트래픽 선 검증으로 모델 배포 위험을 최소화하는 점진적 롤아웃 전략임

## Ⅱ. 구성요소
```text
Load Balancer ---(95%)---> Current Model (v1)
      |
      +--------(5%)------> Canary Model (v2)
                                 |
                                 v
                           Metric Comparator --> Promote / Rollback
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Load Balancer | 트래픽을 비율 기반으로 v1/v2에 분배 | 도로 분기점 신호등 |
| Canary Model | 소량 트래픽을 받는 신규 모델 인스턴스 | 시험 운행 차량 |
| Metric Comparator | v1/v2 성능 지표를 실시간 비교·판정 | 품질 비교 검사관 |
| Promote/Rollback | 비교 결과에 따라 전체 전환 또는 즉시 복구 | 합격/불합격 판정 |

> 요약: 로드밸런서·카나리 인스턴스·지표 비교기·승격/롤백으로 구성됨

## Ⅲ. 절차
```text
Deploy Canary --> Split Traffic --> Compare Metrics --> Promote or Rollback
```
- 1단계: 카나리 배포 — 신규 모델을 별도 인스턴스에 배포(기존 모델 유지)
- 2단계: 트래픽 분할 — 전체 트래픽의 1~5%를 카나리로 라우팅
- 3단계: 지표 비교 — 정확도·지연시간·에러율을 기존 모델과 통계적으로 비교
- 4단계: 승격/롤백 — 기준 충족 시 트래픽을 점진 확대, 미충족 시 즉시 롤백

> 요약: 배포 → 분할 → 비교 → 승격/롤백의 4단계로 안전하게 전환함

## Ⅳ. 문제점
- 소량 트래픽 통계 부족: 카나리 비율이 낮으면 유의미한 성능 차이 판별이 어려움
- 사용자 경험 불균등: 카나리 대상 사용자가 품질 저하를 체감할 수 있음
- 인프라 이중 운영: 두 버전 동시 서빙으로 리소스 비용이 일시적으로 증가함

> 요약: 통계 부족·사용자 불균등·이중 인프라 세 측면에서 비용이 발생함

## Ⅴ. 개선방안
1. 단기: 최소 표본 수 사전 산정으로 통계적 유의성 확보 후 판정
2. 중기: 사용자 세그먼트 기반 카나리 대상 선정으로 영향 범위 제어
3. 장기: 자동 스케일링 연동으로 카나리 승격 시 이중 인프라 비용 최소화

> 요약: 표본 설계·세그먼트·자동 스케일링으로 카나리 배포 부작용을 제어함

## Ⅵ. 전망
- 발전 방향: Progressive Delivery(카나리+Feature Flag) 통합으로 세밀한 롤아웃 제어가 확산됨
- 기술사적 판단: Shadow(258)·A/B(259)와 조합하여 배포 전략 포트폴리오를 구성해야 함
- 기술사 제언: 자동 판정 기준을 사전 정의하여 사람 의존 없는 배포 자동화를 구현해야 함
