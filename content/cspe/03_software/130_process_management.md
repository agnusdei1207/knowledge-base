## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 실행 중인 프로그램인 프로세스의 생명주기 관리 및 CPU 자원 배분 기법 |
| 필요성 | 한정된 CPU 자원의 공평한 분배 및 멀티태스킹 환경의 응답성 확보 |
| 출제 의도 | 상태 전이도, PCB 구조, 스케줄링 알고리즘(Preemptive 등) 이해 |

## Ⅱ. 구성요소
```text
+-----------------------+   +---------------------------+
|   Stack (Local Var)   |   |        PID / Status       |
+-----------------------+   +---------------------------+
|    Heap (Dynamic)     |   |      PC / Registers       |
+-----------------------+   +---------------------------+
|    Data (Global)      |   |    Memory Management      |
+-----------------------+   +---------------------------+
|    Code (Text)        |   |    I/O Status / Open Files|
+-------(Memory)--------+   +----------(PCB)------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| PCB | 프로세스 제어 블록, 프로세스 정보를 담은 자료구조 | 인사 기록부 |
| 상태 전이 | New, Ready, Running, Waiting, Terminated 상태 변화 | 업무 진행 단계 |
| 스케줄러 | CPU를 할당할 프로세스를 선택하는 커널 모듈 | 업무 배정자 |
> 요약: PCB는 프로세스 상태를 저장하며, 스케줄러는 이를 기반으로 CPU를 할당함.

## Ⅲ. 절차
```text
New -> (Admit) -> Ready <----(Timeout)----> Running -> Terminated
                    ^                         |
                    +--- (I/O Done) --- Waiting <--- (I/O Req)
```
1. 생성 및 준비: 프로세스 생성 후 PCB 등록 및 Ready Queue에서 대기.
2. 디스패치: 스케줄러에 의해 선택된 프로세스에 CPU 할당 및 실행 시작.
3. 중단 및 대기: I/O 발생 시 Waiting 상태로 전이, CPU 자원 반납.
4. 종료 및 회수: 작업 완료 후 PCB 제거 및 점유하던 모든 자원 해제.
> 요약: 상태 전이를 통해 여러 프로세스가 CPU를 공유하며 실행되는 메커니즘임.

## Ⅳ. 문제점
- 우선순위가 낮은 프로세스가 무한정 대기하는 기아(Starvation) 현상 발생.
- 잦은 선점형 스케줄링으로 인한 문맥 교환(Context Switch) 비용 누적.

## Ⅴ. 개선방안
- 에이징(Aging) 기법을 도입하여 대기 시간이 긴 프로세스의 우선순위 상향.
- 멀티레벨 피드백 큐(MLFQ) 적용으로 대화형/연산형 프로세스 특성별 최적화.

## Ⅵ. 전망
- 이종 컴퓨팅(Heterogeneous): CPU-GPU-NPU 간 프로세스 스케줄링 최적화 기술 중요.
- 실시간성 강화: 하드웨어 가속 기반의 초저지연 스케줄링 알고리즘 연구 활발.
