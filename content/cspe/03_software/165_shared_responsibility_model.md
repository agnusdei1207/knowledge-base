## 미리 알고가기

- 공유 책임 모델은 클라우드 공급자와 소비자가 보안·운영·규정 준수 책임을 나누는 기준임
- 공급자는 데이터센터·물리 장비·기반 네트워크 등 클라우드 자체의 보안을 담당함
- 소비자는 계정·데이터·애플리케이션과 선택한 서비스의 구성 보안을 담당함
- IaaS·PaaS·SaaS에 따라 운영체제·런타임·애플리케이션 책임자가 달라짐
- 통제 상속은 공급자가 수행한 물리·플랫폼 통제의 감사 증적을 소비자가 활용하는 방식임
- 책임 매트릭스는 통제 항목별 수행·승인·증적 보유 주체를 명시함

## 작성 근거(검토용)

- 공유 책임은 책임 이전이 아니라 서비스 계층별 경계 이동이므로 계층과 통제 주체를 중심에 둠
- 서비스 모델별 물리·관리형 계층(OS·런타임·앱)·데이터 책임을 같은 수준에서 비교하고 통제 증적은 Ⅳ 구성요소에서 다룸
- Ⅴ절은 서비스 범위 확인부터 통제 분해·책임 배정·증적 연결·정기 검증까지의 적용 절차로 구성함
- 제목부터 결론까지 5회 전수 검수하여 공급자·소비자 책임의 누락과 중복을 확인함

## Ⅰ. 개요

- **정의/개념**: 공유 책임 모델은 클라우드 서비스 계층별 보안·운영·규정 준수 책임을 공급자와 소비자에게 배분하는 통제 체계임
- **배경/필요성**: 서비스 사용 후에도 남는 소비자 책임과 공급자 책임을 구분하기 위해 통제별 책임 경계가 필요함

### 쉽게 이해하기 (학습용)
- 클라우드를 사용해도 모든 보안 책임이 공급자에게 넘어가지 않으므로 업무 분담표가 필요함

## Ⅱ. 특징

- 공급자는 물리 인프라와 서비스 기반을 운영하고 소비자는 데이터와 접근 구성을 통제함
- IaaS에서 SaaS로 갈수록 공급자가 운영하는 계층은 늘지만 소비자 데이터 책임은 유지됨
- 같은 서비스에서도 암호화 선택·키 소유·로그 보존 설정에 따라 소비자 책임이 달라짐
- 소비자는 공급자 통제를 상속받아 계약·서비스 문서·감사 보고서에 설정 증적을 결합해 통제 이행을 입증함

### 쉽게 이해하기 (학습용)
- 공급자가 지키는 기반과 소비자가 설정하는 계정·데이터를 연결해야 전체 통제가 완성됨

## Ⅲ. 서비스 모델별 책임 비교

| 책임 항목 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|
| 물리·가상화 | 공급자 운영 | 공급자 운영 | 공급자 운영 |
| OS·런타임·애플리케이션 | 소비자가 OS·런타임·앱 운영 | 공급자 OS·런타임 운영·소비자 앱 운영 | 공급자 OS·런타임·앱 운영·소비자 업무 설정 |
| 데이터·계정 | 소비자 분류·권한·보존 | 소비자 분류·권한·보존 | 소비자 분류·권한·보존 |

> 요약: 관리형 계층이 늘어도 데이터 분류·계정 권한·보존은 소비자가 계속 책임짐.

### 쉽게 이해하기 (학습용)
- SaaS를 사용해도 사용자 계정과 데이터 공개 범위를 정하는 일은 소비자에게 남음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 서비스 계층 목록 | 물리·가상화·OS·런타임·앱·데이터 범위를 식별함 |
| 공급자 책임 문서 | 서비스가 제공하는 운영·보안·감사 범위를 명시함 |
| 소비자 통제 목록 | 계정·구성·패치·데이터·로그 수행 항목을 정함 |
| 책임 매트릭스 | 통제별 수행자·승인자·증적 보유자를 연결함 |
| 구성 정책 | 허용 설정과 위반 조건을 정책 코드로 검사함 |
| 감사 증적 저장소 | 공급자 보고서와 소비자 로그·설정 이력을 보관함 |

```text
공급자 통제 증적 ----+
                    +-> 책임 매트릭스 -> 통제 이행 확인
소비자 설정·로그 ----+
```

> 요약: 책임 매트릭스가 공급자 통제 증적과 소비자 설정·운영 증적을 통제 항목별로 연결함.

### 쉽게 이해하기 (학습용)
- 공급자 보고서와 소비자 로그를 같은 통제 항목 아래 묶어 책임 이행을 증명함

## Ⅴ. 원리 및 절차 흐름도

```text
서비스 범위 확인 -> 통제 항목 분해 -> 책임 주체 배정 -> 증적 연결 -> 정기 검증·개선
```

1. 계약·서비스 문서에서 공급자가 운영하고 보호하는 계층을 확인함
2. 계정·데이터·패치·구성·로그·복구 통제를 세부 항목으로 나눔
3. 통제별 수행자·승인자·증적 보유자를 책임 매트릭스에 배정함
4. 공급자 감사 자료와 소비자 설정·로그를 통제 항목별로 연결함
5. 서비스 변경과 구성 위반을 정기 확인해 책임표와 운영 절차를 갱신함

> 요약: 서비스 계층을 통제로 분해해 책임자와 증적을 연결하고 변경 시 계속 갱신함.

### 쉽게 이해하기 (학습용)
- 해야 할 보안 일을 나누고 담당자와 확인 자료를 붙여 빠진 책임이 없는지 반복 점검함

## Ⅵ. 실무 사례

1. IaaS 서버는 소비자가 게스트 OS를 패치하고 미패치 인스턴스 수·적용 시간을 확인함
2. SaaS 협업 도구는 계정·공유 권한을 정리하고 휴면 계정 수·외부 공유 건수를 확인함

### 쉽게 이해하기 (학습용)
- IaaS에서는 운영체제 패치, SaaS에서는 계정과 공유 설정처럼 소비자 책임의 위치가 달라짐

## Ⅶ. 결론

- 공유 책임 모델은 서비스별 통제 경계를 확인하고 소비자 책임을 운영 절차와 증적으로 연결해야 함

### 쉽게 이해하기 (학습용)
- 맡길 수 있는 기반 운영과 끝까지 남는 데이터·계정 책임을 혼동하지 않아야 함
