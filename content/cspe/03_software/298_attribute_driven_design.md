## Ⅰ. 개요
- 정의: 품질 속성(Quality Attributes) 시나리오를 설계의 주된 동력으로 사용하는 설계 방법론임
- 배경: 기능 중심 설계의 한계를 극복하고 비기능적 요구사항의 체계적 반영 필요
- 출제 의도: 품질 속성 달성을 위한 반복적 아키텍처 분할 및 설계 기법 이해 확인

## Ⅱ. 구성요소
- ASCII 구조도
  [Input: QAs] -> [ADD Iteration] -> [Subsystems]
                       |
               [Tactics/Patterns]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 품질 시나리오 | 구체적 상황에서의 품질 목표 기술 | 안전 테스트 조건 |
| 설계 전술(Tactics) | 품질 속성 달성을 위한 기술적 조치 | 보강 공법 |
| 반복 분할 | 시스템을 하위 요소로 점진적 분해 | 조립식 구조 |
> 요약: 품질 시나리오 기반으로 전술과 패턴을 적용하여 점진적으로 구조를 상세화함

## Ⅲ. 절차
- ASCII 흐름도
  Step 1~3: Inputs -> Step 4~6: Design -> Step 7~8: Review
- 4단계 설명
1. Inputs: 설계 대상 모듈 선정 및 제약 사항, 품질 속성 시나리오 확인함
2. Selection: 해당 단계에서 집중할 핵심 품질 속성 및 시나리오 선택함
3. Tactics/Pattern: 선택된 속성을 만족시키는 기술 전술 및 패턴 적용함
4. Instantiation: 컴포넌트와 책임을 할당하고 인터페이스를 정의함
> 요약: 핵심 품질 속성을 선택하고 이를 해결할 전술을 적용하여 모듈을 구체화함

## Ⅳ. 문제점
- 소규모 시스템에 전체 ADD 절차와 산출물을 적용하면 설계 비용이 구현 규모보다 커질 수 있음

## Ⅴ. 개선방안
- 프로젝트 규모와 위험 수준에 따라 핵심 품질 시나리오·전술·결정 기록만 남기는 경량 ADD를 적용함

## Ⅵ. 전망
- 발전 방향: 클라우드 네이티브 환경의 동적 품질 속성 대응을 위한 자동 ADD 프레임워크 연구
- CSF: 품질 속성 간의 우선순위 결정(Prioritization)이 성공적인 ADD 수행의 전제 조건임
