## Ⅰ. 개요
- **정의**: SW 규모(KLOC/FP)를 입력으로 공수와 일정을 산출하는 알고리즘 기반 비용 예측 모델임
- **배경/필요성**: 전문가 판단만으로는 예측 편향이 발생하므로 수학적 모델로 객관성을 확보할 필요가 있음
- **비유**: 차량 연비 공식에 주행 거리를 넣으면 연료 소요량이 나오는 구조와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| COCOMO 모델 단계별 특성 비교 | Basic/Intermediate/Detailed, COCOMO II 구분 | 모델 계수 암기보다 구조 이해 중심 |

> 요약: 규모 기반 수학 모델로 공수와 일정을 객관적으로 산출하는 비용 예측 기법임

## Ⅱ. 구성요소
```text
[COCOMO 산출 구조]
  규모(Size: KLOC) ---> Effort = a x (Size)^b
        |
        v
  비용 동인(Cost Drivers) -> 보정 계수(EAF)
        |
        v
  공수(Effort: PM) -------> Duration = c x (Effort)^d
        |
        v
  일정(Duration: Month)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 규모 입력 | KLOC 또는 FP를 LOC로 변환한 값임 | 주행 거리 |
| 비용 동인 | 제품 복잡도, 팀 역량 등 15~17개 조정 인자임 | 도로 조건 계수 |
| 모델 계수 | 프로젝트 유형(Organic/Semi-detached/Embedded)별 `a`, `b`, `c`, `d` 값임 | 차종별 연비 계수 |

> 요약: 규모-비용 동인-모델 계수로 공수와 일정을 산출함

## Ⅲ. 절차
```text
프로젝트 유형 분류 --> 규모 산출 --> 공수 산출 --> 일정 도출
```
- 1단계: 프로젝트 유형 분류 — Organic/Semi-detached/Embedded 중 해당 유형을 선택함
- 2단계: 규모 산출 — KLOC 또는 FP(096 참조) 기반으로 개발 규모를 확정함
- 3단계: 공수 산출 — `Effort = a x (KLOC)^b x EAF` 공식으로 인월을 계산함
- 4단계: 일정 도출 — `Duration = c x (Effort)^d` 공식으로 개발 기간을 산출함

> 요약: 유형 분류-규모-공수-일정 순서로 비용을 산출함

## Ⅳ. 문제점
- 계수 의존성: 모델 계수가 특정 환경 데이터에서 도출되어 타 조직 적용 시 오차가 큼
- 규모 선행 필요: 정확한 KLOC 추정이 선행되어야 하나 초기 단계에서 규모 파악이 곤란함
- 현대 개발 미반영: 애자일, 마이크로서비스 등 현대 개발 방식의 특성이 모델에 미반영됨

> 요약: 계수 이식성, 규모 선행 필요, 현대 개발 미반영이 COCOMO의 한계임

## Ⅴ. 개선방안
1. 단기: 조직 과거 실적으로 모델 계수를 캘리브레이션하여 이식성을 확보함
2. 중기: COCOMO II의 Application Composition 모델을 활용하여 초기 단계 예측을 보완함
3. 장기: 애자일 메트릭(스토리 포인트 속도)과 COCOMO를 결합한 하이브리드 예측 체계를 구축함

> 요약: 캘리브레이션-초기 예측 보완-하이브리드 모델 순서로 COCOMO를 현대화함

## Ⅵ. 전망
- 발전 방향: 머신러닝 회귀 모델이 전통 COCOMO의 고정 계수를 대체하는 추세임
- 기술사적 판단: COCOMO는 SW 예측(095 참조) 체계의 기본 프레임으로 개념적 가치를 유지함
- 기술사 제언: 모델 결과를 유일한 근거로 삼지 말고 전문가 판단, 유추와 삼각 검증할 필요
