## Ⅰ. 개요
- **정의**: 프로세스를 로컬 메모리 노드에 배치하여 원격 접근 지연을 최소화하는 스케줄링 기법
- **배경/필요성**: 멀티소켓 서버에서 원격 노드 메모리 접근 시 로컬 대비 2~3배 지연이 발생하여 성능 저하가 큼
- **비유**: 같은 층 복사기를 쓰면 빠르지만, 다른 층 복사기까지 가면 느린 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NUMA 토폴로지와 스케줄링 연계 이해 | 로컬 vs 원격 지연 차이, 친화성 정책 | 단순 CPU 스케줄링과 혼동 금지 |

> 요약: 스레드를 로컬 메모리 노드에 고정하여 원격 접근 비용을 줄이는 스케줄링 전략임

## Ⅱ. 구성요소
```text
CPU0 -- Local Memory 0       CPU1 -- Local Memory 1
   \                            /
    +-- Interconnect (QPI/UPI) -+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| NUMA 노드 | CPU와 로컬 메모리의 쌍으로 구성된 단위 | 한 층에 배치된 사무실과 복사기 |
| Interconnect | 노드 간 데이터를 전달하는 고속 버스(QPI/UPI) | 층간 연결 통로 |
| 친화성 정책 | 스레드를 특정 노드에 바인딩하는 OS 정책 | 직원을 같은 층에 배정하는 규칙 |

> 요약: CPU-메모리 쌍인 노드와 노드 간 인터커넥트, 친화성 정책으로 구성됨

## Ⅲ. 절차
```text
토폴로지 탐색 -> 메모리 할당 -> 스레드 배치 -> 밸런싱
```
- 1단계: OS가 부팅 시 NUMA 토폴로지(노드 수, 거리 행렬)를 탐색함
- 2단계: 프로세스 생성 시 로컬 노드에서 메모리 페이지를 우선 할당함
- 3단계: 스케줄러가 해당 메모리와 같은 노드의 CPU에 스레드를 배치함
- 4단계: 부하 불균형 시 마이그레이션 비용을 계산하여 선택적 밸런싱 수행함

> 요약: 토폴로지 탐색 후 메모리와 스레드를 같은 노드에 배치하고 선택적으로 밸런싱함

## Ⅳ. 문제점
- 부하 편중: 특정 노드에 스레드 집중 시 로컬 메모리 부족으로 원격 할당 발생
- 마이그레이션 비용: 스레드 이동 시 캐시 무효화와 TLB 플러시로 일시적 성능 저하 발생
- 설정 복잡성: 워크로드별 최적 친화성 정책이 달라 수동 튜닝 부담이 큼

> 요약: 부하 편중, 마이그레이션 비용, 수동 튜닝 복잡성이 주요 문제임

## Ⅴ. 개선방안
1. 단기: AutoNUMA(자동 페이지 마이그레이션)로 부하 편중 시 페이지를 재배치함
2. 중기: 스케줄러에 마이그레이션 비용 임계값을 도입하여 불필요한 이동을 억제함
3. 장기: 워크로드 프로파일 기반 ML 모델로 친화성 정책을 자동 결정함

> 요약: 자동 페이지 이동, 임계값 기반 억제, ML 기반 자동 정책으로 개선 가능함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 풀 환경에서 NUMA 계층이 3단계 이상으로 확장될 전망임
- 기술사적 판단: 고성능 컴퓨팅과 DB 워크로드에서 NUMA 인지 설계는 필수 역량임
- 기술사 제언: 하드웨어 토폴로지 변화에 대응하는 적응형 스케줄링 연구가 필요함
