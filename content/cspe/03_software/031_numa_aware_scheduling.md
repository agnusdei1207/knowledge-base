## 핵심 인사이트 (3줄 요약)
- CPU가 원격 노드(Remote)의 메모리보다 자신과 동일한 노드(Local)의 메모리를 우선 접근하도록 OS 레벨에서 묶어주는 튜닝 기법.
- CPU 코어 급증으로 인한 시스템 버스 대역폭 병목(UMA의 한계)을 타개하기 위한 하드웨어-소프트웨어 통합 최적화.
- 노드 내 메모리 고갈 시 무분별한 스왑(Swap)이 발생하는 Zone Reclaim 장애를 막기 위한 Interleave(분산) 전략의 이해가 필수.

## Ⅰ. 개요 및 필요성
- **개요**: CPU(소켓)와 로컬 메모리가 한 세트로 묶인 노드(Node)들로 구성된 NUMA 아키텍처에서, 메모리 지역성(Locality)을 극대화하는 OS 스케줄링 메커니즘.
- **필요성**: 모든 CPU가 단일 버스를 공유하던 기존 UMA 방식은 코어가 늘어날수록 병목이 극심해짐. NUMA를 도입했으나, OS가 무작위로 메모리를 할당하면 CPU가 타 노드까지 원정(Remote Access)을 가야 하므로 대역폭 낭비와 엄청난 지연(Latency)이 발생함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **First-Touch Policy (최초 쓰기 정책)**: 스레드가 프로세스 메모리에 '최초로 기록(Write)'하는 순간, 그 스레드가 돌고 있는 CPU의 노드 메모리에 물리 페이지를 강제 할당함.
- **Local vs Remote Access**: 자기 노드 메모리를 읽으면 빠르지만, 타 노드 메모리를 읽으려면 인터커넥트 버스(UPI 등)를 거쳐야 해 느림.

```text
   [ Node 0 ]                       [ Node 1 ]
 +------------+                   +------------+
 |   CPU 0    |                   |   CPU 1    |
 +-----+------+                   +-----+------+
       | (Local Access: 빠름)           |
 +-----+------+                   +-----+------+
 |  Memory 0  | <==== (UPI) ====> |  Memory 1  | 
 +------------+   (Remote Access) +------------+
                   (지연 발생)
```

## Ⅲ. 비교 및 연결
| 정책 (numactl) | 동작 방식 | 적용 시나리오 장단점 |
|---|---|---|
| **Node Binding (고정)** | 특정 프로세스를 0번 노드에만 실행되도록 가둠 | 캐시 활용이 극대화되는 HPC 모델이나 분할된 다중 Redis 인스턴스에 완벽함 |
| **Interleaving (분산)** | 메모리를 노드 구분 없이 라운드 로빈으로 골고루 할당 | 대용량 JVM 힙(Heap)이나 단일 대형 DB 운영 시 특정 노드 OOM에 의한 시스템 스왑 방지 |
| **AutoNUMA (자동)** | 백그라운드 데몬이 메모리 접근 빈도를 계산해 핫 노드로 이주시킴 | 관리 포인트는 적으나 마이그레이션 자체의 오버헤드 존재 |

## Ⅳ. 실무 적용 및 기술사 판단
- **Zone Reclaim 장애 판단**: 시스템 전체 메모리가 40%나 남아있는데도 MySQL이나 SAP HANA DB가 갑자기 느려지며 디스크 Swap을 사용하는 현상이 빈번함.
- **해결 방안 (트러블슈팅)**: 특정 노드(Node 0)의 메모리가 다 찼을 때 타 노드(Node 1)의 메모리를 빌려 쓰지 않고 기존 캐시를 비우거나 스왑을 강행하는 `vm.zone_reclaim_mode = 1` 기본 설정이 원인임. 이를 `0`으로 끄고, DB는 반드시 `numactl --interleave=all` 옵션을 주어 구동시켜야 치명적 장애를 방지할 수 있음.
---
## Ⅴ. 기대효과 및 결론
- NUMA 인지 스케줄링은 하드웨어 토폴로지를 소프트웨어가 적극 반영하여 멀티 소켓 대형 서버의 I/O 성능을 최대 2~3배 끌어올림.
- 물리적 메모리 슬롯의 한계가 다가오면서, 향후에는 PCIe 기반의 CXL(Compute Express Link) 기술을 통한 외부 메모리 풀링(Disaggregated Memory)이라는 확장된 개념으로 진화하고 있음.

### 👶 어린이를 위한 3줄 비유 설명
1. 서울 지사 직원(CPU 0)은 서울 서류창고(Node 0)에서, 부산 지사 직원은 부산 서류창고에서 일하는 게 제일 빨라요.
2. 그런데 서울 직원이 부산 창고까지 서류를 가지러 가면(Remote Access) 길에서 시간을 다 버리게 돼요.
3. 그래서 컴퓨터(OS)가 알아서 "너는 서울이니까 서울 창고만 써!"라고 딱 정해주는(NUMA 인지) 똑똑한 기술이랍니다.
