# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: NUMA 구조에서 메모리 접근 지연을 최소화하기 위해 프로세스를 데이터가 있는 로컬 노드에 할당하는 운영체제 스케줄링 기법.
- **왜 필요한가**: 원격 노드 메모리 접근 시 발생하는 트래픽 병목과 지연(Remote Access Latency)을 방지하여 다중 프로세서 성능을 극대화해야 한다.
- **핵심 직관**: CPU와 메모리를 한 세트(노드)로 묶고, 작업할 때 남의 동네(원격 노드)로 가지 않도록 자기 동네(로컬 노드)에서만 놀게 만드는 것.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| NUMA (Non-Uniform Memory Access) | 프로세서마다 접근 시간이 다른 메모리 구조 | 동네마다 마트가 있는 도시 |
| 노드 (Node) | CPU 코어와 로컬 메모리의 결합 단위 | 하나의 동네 |
| 메모리 어피니티 (Memory Affinity) | 프로세스와 특정 노드의 메모리 간 결속력 | 단골 마트 지정 |

## 깊이 이해
- **배경·문제의식**: UMA(SMP) 환경에서는 코어 수가 늘어나면 단일 메모리 버스에 병목이 발생한다. 이를 해결하기 위해 NUMA가 도입되었으나, 프로세스가 자신과 먼 노드의 메모리에 접근하면 UMA보다 오히려 성능이 저하되는 원격 메모리 접근 페널티가 발생한다.
- **작동 원리**: 스케줄러가 프로세스의 상태와 메모리 할당 위치를 추적한다. 프로세스가 재개될 때, 이전 캐시 데이터나 할당된 메모리가 존재하는 노드의 코어에 우선적으로 배정(Processor Affinity)한다. 메모리 할당도 프로세스가 실행 중인 노드의 로컬 메모리에서 먼저 이루어지게 한다(First-touch Policy).
- **비유**: 자기 동네 마트(로컬 메모리)에서 물건을 사면 5분 만에 오지만, 옆 동네 마트(원격 메모리)에 가면 20분이 걸리므로, 심부름꾼(프로세스)을 반드시 물건이 있는 동네에서만 일하게 하는 것과 같다.
- **구체 예시**: 2소켓 NUMA 서버(CPU 0, CPU 1)에서 DB 스레드가 CPU 0의 메모리 영역에 버퍼 풀을 생성했다면, 운영체제는 이 스레드를 CPU 1로 마이그레이션하지 않고 가급적 CPU 0에서 실행하도록 고정(Pinning)한다.
- **흔한 오해·주의점**: NUMA 인지 스케줄링이 항상 로컬 노드 할당을 보장하지는 않는다. 특정 노드에 부하가 집중되면 성능 향상보다 로드 밸런싱이 우선되어 어쩔 수 없이 원격 노드로 프로세스를 마이그레이션할 수 있다.

## 연결 개념
- 스레드 어피니티 (Thread Affinity)
- 캐시 코히런시 (Cache Coherency)
- 스핀락 (Spinlock)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 데이터와 프로세싱의 지역성(Locality)을 극대화하는 CPU-메모리 바인딩 기술.
> 2. **가치**: 다중 소켓 환경에서 메모리 접근 지연 시간(Latency) 감소 및 버스 대역폭 병목 해소.
> 3. **판단 포인트**: 특정 노드 부하 편중(Imbalance)과 메모리 지역성 보장 간의 트레이드오프 조율이 핵심.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NUMA 환경의 성능 저하 원인과 해결책 이해 | 로컬/원격 메모리 접근 지연 차이, 프로세서 어피니티 | 메모리 병목 원인 누락 |
| 스케줄링 최적화 방안 적용 역량 | First-touch 정책, 스레드 고정(Pinning) | 스케줄러를 UMA와 혼동 |

> 요약: NUMA 아키텍처의 원격 메모리 접근 페널티를 프로세스-노드 친화도 기반 스케줄링으로 해결하는 방안 제시.

---

## Ⅰ. 개요 및 필요성
- 개요: NUMA 구조에서 메모리 접근 지연을 최소화하기 위해 프로세스를 데이터가 있는 로컬 노드에 할당하는 최적화 스케줄링 기법.
- 배경: 다중 코어 증가로 인한 UMA(SMP) 메모리 버스 병목 한계 극복 위해 NUMA 도입.
- 필요성: 원격 노드 메모리 접근 시 발생하는 QPI/UPI 인터커넥트 병목 및 응답 지연(Latency) 방지.

---

## Ⅱ. 구조 및 구성요소

```text
프로세스 실행 요청 -> 스케줄러 큐 할당 -> 노드 토폴로지 분석 -> 메모리 친화도 평가 -> 코어 바인딩 및 실행
                      |                    |                  |
                      +-> 부하 모니터링    +-> 원격 노드 회피 +-> First-touch 할당
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Node Topology | CPU, 메모리, 인터커넥트 연결 구조 매핑 | ACPI 테이블 기반 정보 수집 |
| Affinity Manager | 프로세스와 특정 노드 간 친화도 점수 계산 | 로컬 캐시 히트율 고려 |
| Load Balancer | 노드 간 CPU 사용률 불균형 해소 | 마이그레이션 페널티와 비교 연산 |
| Memory Allocator | First-touch 정책으로 로컬 메모리 우선 할당 | 페이지 부재 시 원격 할당 허용 |

> 요약: 스케줄러가 노드 토폴로지를 분석해 친화도 기반으로 코어를 바인딩하고 로컬 메모리를 할당하는 구조.

---

## Ⅲ. 동작원리 및 흐름도

```text
프로세스 생성 -> First-touch 메모리 할당 -> 실행 대기 큐 배치 -> 스케줄링 판단 (로컬 vs 원격) -> 실행 및 마이그레이션 통제
```

- 1단계 [메모리 할당]: 프로세스가 처음 메모리에 접근할 때 해당 코어가 속한 노드에 페이지 할당 (First-touch).
- 2단계 [어피니티 평가]: 프로세스의 이전 실행 위치 및 할당된 메모리 노드를 기반으로 가중치 계산.
- 3단계 [코어 스케줄링]: 친화도 점수가 가장 높은 로컬 노드의 대기 큐에 프로세스 삽입 및 실행.
- 4단계 [로드 밸런싱 통제]: 노드 간 부하 불균형 임계치 초과 시에만 제한적으로 원격 노드로 마이그레이션.

> 요약: First-touch 정책으로 로컬 영역을 확보한 후, 친화도 평가를 거쳐 마이그레이션을 억제하며 실행하는 과정.

---

## Ⅳ. 특징
- 처리량 극대화: 로컬 메모리 접근을 통한 캐시 히트율 상승 및 메모리 지연 최소화.
- 대역폭 병목 해소: 노드 간 인터커넥트(QPI/UPI) 트래픽 감소로 전체 시스템 버스 여유 확보.
- 트레이드오프: 로컬 할당을 고집할 경우 특정 노드에 자원이 고갈(Imbalance)되는 부하 편중 발생 위험.

> 요약: 메모리 지연 최소화의 장점이 있으나, 노드 간 부하 편중을 방어해야 하는 한계가 존재.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | UMA 스케줄링 | NUMA 인지 스케줄링 | 선택 기준 |
|:---|:---|:---|:---|
| 대상 구조 | 단일 메모리 버스 공유 (SMP) | 다중 노드 분산 메모리 | CPU 소켓 수 및 아키텍처 |
| 메모리 할당 | 위치 무관 균등 할당 | First-touch 등 로컬 우선 | 메모리 접근 지연 민감도 |
| 로드 밸런싱 | 전역 큐 기반 즉각 마이그레이션 | 로컬 큐 기반 마이그레이션 억제 | 캐시/메모리 어피니티 중요도 |

> 요약: 물리적 서버 아키텍처가 NUMA인 경우 메모리 접근 페널티를 고려하여 NUMA 인지 스케줄링을 필수 적용.

**부하 편중 리스크 및 대응:**
- 특정 노드 자원 고갈: First-touch 집중 → Interleave 할당 정책 병행 적용 (지표: 노드별 메모리 가용량)
- 마이그레이션 스래싱: 과도한 밸런싱 개입 → 이주 페널티 임계치(Threshold) 상향 (지표: 노드 간 문맥 교환 횟수)

---

## Ⅵ. 실무 적용 및 결론

**대규모 DB 및 가상화 적용 방안:**
1. CPU Pinning 적용: KVM/VMware 환경에서 vCPU를 물리적 NUMA 노드에 1:1 고정 매핑.
2. HugePages 활용: TLB 미스 페널티를 줄이기 위해 NUMA 노드별로 대용량 페이지(2MB/1GB) 사전 할당.
3. NUMA Interleaving: 네트워크 패킷 처리 등 전역 메모리 접근이 잦은 워크로드는 노드 간 교차 할당 강제.

**결론:**
- 기술사 판단: 인메모리 DB나 고성능 컴퓨팅(HPC) 워크로드에서는 NUMA 인지 스케줄링과 수동 CPU Pinning을 결합해야 성능 저하를 막을 수 있다.
- 향후 방향: CXL(Compute Express Link) 기반 메모리 풀링 아키텍처와 결합하여 동적 자원 재배치 스케줄링으로 진화할 것.
