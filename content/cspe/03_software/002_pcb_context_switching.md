## Ⅰ. 개요
- **정의**: PCB에 프로세스 상태를 저장·복원하여 CPU를 다른 프로세스에 넘기는 전환 기법임
- **배경/필요성**: 다중 프로세스 환경에서 CPU를 시분할 공유하려면 현재 실행 상태를 보존하는 메커니즘이 필요함
- **비유**: 책갈피를 꽂아 두고 다른 책을 읽다가 돌아오면 이어 읽는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 컨텍스트 스위칭의 오버헤드 이해 | PCB 저장 항목(PC, SP, 레지스터, 상태) | 스위칭 자체가 유효 작업이 아닌 순수 비용임을 명시 |

> 요약: PCB 기반 컨텍스트 스위칭은 멀티태스킹의 핵심이나 오버헤드 관리가 중요함

## Ⅱ. 구성요소
```text
+--- PCB (Process Control Block) ---+
| PID          | Process ID         |
| State        | Ready/Run/Wait     |
| PC           | Program Counter    |
| Registers    | CPU Register Set   |
| Memory Info  | Base/Limit/Page Tbl|
| I/O Status   | Open File List     |
| Priority     | Scheduling Info    |
+-----------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Program Counter | 다음 실행할 명령어 주소를 저장함 | 책갈피 위치 |
| CPU 레지스터 셋 | 연산 중간값을 보관하는 레지스터 전체를 저장함 | 계산기 화면의 중간 결과 |
| 메모리 관리 정보 | 페이지 테이블, 베이스/리밋 레지스터 등을 포함함 | 사물함 번호표 |

> 요약: PCB는 프로세스 복원에 필요한 모든 상태를 담는 자료구조임

## Ⅲ. 절차
```text
Running P1 --[인터럽트]--> Save PCB(P1) --> Load PCB(P2) --> Running P2
```
- 1단계: 인터럽트 또는 시스템 호출이 발생하여 현재 프로세스 P1의 실행을 중단함
- 2단계: P1의 PC, 레지스터, 상태를 PCB에 저장함
- 3단계: 스케줄러가 다음 실행할 프로세스 P2를 선택함
- 4단계: P2의 PCB에서 상태를 복원하고 CPU 제어권을 P2에 넘김

> 요약: 저장-선택-복원의 3단 과정으로 CPU 소유권이 전환됨

## Ⅳ. 문제점
- 전환 오버헤드: 레지스터·메모리 매핑 저장/복원에 수 us 소요 — 잦은 전환 시 CPU 유효 사용률 저하됨
- 캐시 무효화: 전환 시 L1/L2 캐시·TLB가 플러시됨 — 새 프로세스가 Cold Start로 지연됨
- PCB 비대화: 프로세스 수 증가 시 PCB 테이블이 커짐 — 커널 메모리 소비가 증가함

> 요약: 전환 빈도에 비례하여 오버헤드·캐시 미스·메모리 비용이 증가함

## Ⅴ. 개선방안
1. 단기: 타임 슬라이스를 적정 수준으로 조정하여 불필요한 전환 빈도를 줄임
2. 중기: TLB 태깅(ASID)으로 전환 시 TLB 플러시를 회피함
3. 장기: 스레드 단위 전환(001 참조) 또는 유저 레벨 스케줄링으로 커널 전환 횟수를 최소화함

> 요약: 전환 빈도 제어, 캐시 보존, 경량 전환으로 오버헤드를 줄임

## Ⅵ. 전망
- 발전 방향: 하드웨어 지원 컨텍스트 스위칭(Intel FRED 등)으로 전환 비용이 감소하는 추세임
- 기술사적 판단: 컨테이너·서버리스 환경에서 경량 전환의 중요성이 증대됨
- 기술사 제언: 워크로드별 전환 빈도를 모니터링하고 타임 슬라이스를 동적 조정할 필요
