## Ⅰ. 개요
- 정의: OS가 프로세스 정보를 저장하는 PCB와 CPU 사용권을 교체하는 컨텍스트 스위칭
- 배경: 시분할 시스템에서 중단된 프로세스를 같은 지점에서 재개하려면 상태 저장이 필요함
- 출제 의도: 프로세스 상태 저장/복원 메커니즘과 그에 따른 성능 부하 이해

## Ⅱ. 구성요소
```
+--------------------------+
| Process Control Block    |
+--------------------------+
| PID / State / PC         |
| Registers / Memory Limits|
| List of Open Files       |
+--------------------------+
```
| 구성요소 | 설명 | 저장 내용 |
| :--- | :--- | :--- |
| PID | 프로세스를 식별하기 위한 고유 번호 | 프로세스 식별자 |
| PC | 다음에 실행할 명령어의 주소 저장 | 재개 위치 |
| 레지스터 | 누산기, 인덱스 레지스터 등 CPU 상태 정보 | 연산 중간 상태 |
> 요약: PCB는 프로세스의 모든 메타데이터를 담고 있는 데이터 구조체임.

## Ⅲ. 절차
```
[P1 실행] -> [Interrupt] -> [Save P1 to PCB1] -> [Load P2 from PCB2] -> [P2 실행]
```
1. 실행 중인 P1에 인터럽트 또는 시스템 호출 발생하여 커널 모드 진입
2. 현재 CPU 내 레지스터 정보 및 PC 값을 PCB1에 저장 (Save Context)
3. 스케줄러가 다음에 실행할 P2를 선택하고 PCB2에서 정보 로드 (Restore Context)
4. CPU 제어권이 P2로 넘어가며 중단되었던 지점부터 재실행
> 요약: 상태 저장과 복원을 통해 중단된 작업을 이어서 수행함.

## Ⅳ. 문제점
- 원인: 잦은 스위칭 발생 시 실제 작업보다 오버헤드(Overhead) 비용이 더 커짐
- 원인: 캐시 메모리의 데이터가 무효화되어 캐시 미스(Cache Miss) 빈도 증가함

## Ⅴ. 개선방안
- (단기) 타임 슬라이스(Time Slice) 크기를 적절히 조정하여 오버헤드 최소화
- (중기) 멀티코어 환경에서 프로세스 친화도(Affinity) 설정으로 캐시 재사용률 개선
- (장기) 마이크로커널 아키텍처 개선 및 하드웨어 가속 스위칭 기술 도입

## Ⅵ. 전망
- 고성능 연산 환경에서는 ASID처럼 주소 공간 전환 비용을 줄이는 하드웨어 지원이 활용됨
- 서버리스(Serverless) 및 마이크로 VM 환경에서 콜드 스타트 억제를 위한 스냅샷 기반 복구 기술과 연계됨

## 작성 근거(검토용)

- PCB는 예시보다 어떤 실행 상태를 저장해 재개하는지가 중심이므로 PID, PC, 레지스터의 저장 역할을 드러냄
- 컨텍스트 스위칭 개선은 성능 단정이 아니라 전환 비용, 캐시 재사용, 주소 공간 전환 비용 절감으로 표현해야 함
