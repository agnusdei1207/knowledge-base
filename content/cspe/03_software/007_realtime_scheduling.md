## 미리 알고가기

- 주기: 주기 작업이 반복 도착하는 시간 간격임
- 마감시간: 작업이 실행을 완료해야 하는 시점임
- 스케줄 가능성: 모든 작업이 마감시간 안에 완료되는지 판정하는 성질임

## 작성 근거(검토용)

- RM과 EDF는 정적·동적 우선순위보다 실제 기준인 주기·절대 마감시간으로 비교함
- 우선순위 계산·선점·완료·마감 위반 판정을 실제 실행 순서로 구성함
- 제어 루프와 소프트 실시간 서버를 분리해 마감 위반율과 선점 지연을 검증함

## Ⅰ. 개요
- **정의/개념**: 실시간 스케줄링은 작업의 주기·실행시간·마감시간으로 우선순위와 선점을 결정해 완료 시점을 통제하는 기법임
- **배경/필요성**: 제어·미디어 작업의 완료 시점 제약을 만족하기 위해 마감시간 기반 실행 순서가 필요함

## Ⅱ. 특징

- RM은 주기가 짧은 작업에 높은 고정 우선순위를 부여함
- EDF는 절대 마감시간이 이른 작업을 실행 시점마다 우선 선택함
- 높은 우선순위 작업이 도착하면 현재 작업을 선점함
- 작업 집합의 실행시간·주기·마감시간으로 스케줄 가능성을 사전에 검증함

## Ⅲ. 종류 및 비교

| 판단 기준 | RM | EDF |
|:---|:---|:---|
| 우선순위 기준 | 작업 주기 | 절대 마감시간 |
| 우선순위 변화 | 작업별 고정 | 준비 작업 상태에 따라 변경 |
| 필요한 작업 정보 | 주기·최악 실행시간 | 마감시간·최악 실행시간 |
| 스케줄 가능성 판정 | 고정 우선순위 이용률·응답시간 분석 | 전체 이용률·수요 분석 |
| 과부하 영향 | 낮은 우선순위 작업부터 마감 위반 | 마감 임박 작업이 연속 선점 가능 |
| 적합 조건 | 주기적 제어 작업 | 마감시간이 다양한 작업 |

> 요약: RM은 작업 주기로 고정 우선순위를, EDF는 절대 마감시간으로 동적 우선순위를 정함.

## Ⅳ. 구성요소 및 구조
```
[ RM: Static Priority ]      [ EDF: Dynamic Priority ]
P1 (Short Period) : High     P1 (Near Deadline) : High
P2 (Long Period)  : Low      P2 (Far Deadline)  : Low
```
| 구성요소 | 설명 | 우선순위 기준 |
| :--- | :--- | :--- |
| 작업 모델 | 주기·최악 실행시간·마감시간을 정의함 | 스케줄 가능성 입력 |
| 준비 큐 | 실행 가능한 작업을 우선순위 순서로 보관함 | 다음 실행 후보 |
| 선점 타이머 | 작업 도착과 실행 예산 만료를 통지함 | 재스케줄 시점 |
| 마감 감시기 | 완료 시각과 마감시간을 비교함 | 마감 위반 판정 |
> 요약: RM은 주기 기반 정적 할당, EDF는 마감 임박도 기반 동적 할당 방식임.

## Ⅴ. 원리 및 절차 흐름도
```
[Task Arrival] -> [Priority Calculation] -> [Preemption] -> [Execution]
```
1. **작업 도착**: 주기 또는 이벤트에 따라 작업을 준비 큐에 넣음
2. **우선순위 계산**: RM은 주기, EDF는 절대 마감시간으로 실행 순서를 정함
3. **실행·선점**: 우선순위가 높은 작업이 준비되면 현재 작업을 선점함
4. **마감 판정**: 완료 시각을 마감시간과 비교하고 다음 작업을 선택함
> 요약: RM과 EDF는 각각 작업 주기와 절대 마감 시간을 기준으로 실행 순서와 선점 여부를 결정함.

## Ⅵ. 실무 사례

1. RTOS 제어 루프는 RM으로 고정 우선순위를 배정하고 최악 응답시간과 마감 위반율을 확인함
2. 미디어 처리 서버는 EDF로 프레임 마감시간을 정렬하고 선점 지연과 지연 프레임 비율을 확인함

## Ⅶ. 결론

- 실시간 스케줄링은 작업의 주기·최악 실행시간·마감시간으로 우선순위와 스케줄 가능성을 판정함
