# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 멀티레벨 피드백 큐(MLFQ)는 우선순위가 다른 **여러 개의 Ready 큐**를 두고, 프로세스의 **실행 이력(피드백)**에 따라 큐 사이를 이동(강등·승급)시키는 동적 스케줄링 기법이다.
- **왜 필요한가**: 프로세스가 I/O 바운드인지 CPU 바운드인지 **미리 알 수 없다**. 실행 시간을 몰라도 SJF의 효과(짧은 작업 우선)를 얻으면서 기아까지 막으려면, 관찰한 행동으로 우선순위를 계속 고쳐야 한다. (선점·문맥 전환·응답 시간 등 스케줄링 일반 배경은 004 참조)
- **핵심 직관**: 놀이공원의 VIP줄(상위 큐)과 일반줄(하위 큐)이다. 한 기구만 타고 빠지는 손님(I/O 바운드)은 VIP에 남기고, 하루 종일 붙어 타는 손님(CPU 바운드)은 일반줄로 내려 회전율을 지킨다.

## 핵심 용어 정리 (내부에 등장하는 것들)

스케줄링 공통 용어(선점·타임 퀀텀·기아·에이징·I/O 바운드·CPU 바운드)의 정의와 비유는 004 용어표를 따르고, 여기서는 MLFQ 고유 용어만 세운다. 맨 위가 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 다단계 큐 (상위 키워드) | 우선순위별로 분리된 여러 개의 Ready 큐 | VIP줄·일반줄·후순위줄 |
| 피드백 (Feedback) | 과거 실행 행동을 근거로 우선순위를 되먹임 조정 | 오래 붙어 타면 일반줄로 강등 |
| 강등 (Demotion) | 퀀텀을 다 쓴 프로세스를 한 단계 아래 큐로 내림 | 오래 탄 손님을 뒷줄로 이동 |
| 승급/부스트 (Boost) | 대기가 길어진 프로세스를 상위 큐로 올림(에이징 구현) | 오래 기다린 일반 손님을 VIP로 승급 |
| 부스트 주기 S | 모든 프로세스를 최상위 큐로 되돌리는 시간 간격 | "S초마다 줄 전체 리셋" 타이머 |
| MLQ (고정 다단계 큐) | 큐 간 이동이 없는 정적 다단계 큐(피드백 없음) | 한번 정한 줄을 끝까지 고정 |
| 어뷰징/게이밍 (Gaming) | 퀀텀 만료 직전 I/O를 흉내 내 강등을 회피하는 꼼수 | 시간 다 되기 직전 잠깐 일어나 자리 유지 |
| 지터 (Jitter) | 주기적 작업의 실행 간격이 들쭉날쭉한 편차 | 음악이 끊겼다 이어졌다 하는 떨림 |

## 깊이 이해
- **배경·문제의식**: 004가 보인 대로 FCFS는 호위 효과, SJF는 실행 시간 예측 불가·기아, RR은 오버헤드라는 한계가 있다. MLFQ가 새로 여는 질문은 "**실행 시간을 모르는 채로 어떻게 짧은 작업을 먼저 처리할까**"이다. 답은 "최근 행동을 관찰해 짧게 쓰던 작업을 계속 위에 두는 것"이다.
- **작동 원리 (규칙)**:
  1. 새 프로세스는 최상위 큐(Q0)에 진입한다(가장 짧은 퀀텀).
  2. 퀀텀을 다 소진하면 CPU 바운드로 보고 한 단계 아래 큐로 강등한다.
  3. 퀀텀 안에 스스로 I/O로 빠지면 I/O 바운드로 보고 현재 큐를 유지한다.
  4. 하위 큐일수록 퀀텀을 길게 줘 CPU 바운드의 문맥 전환 횟수를 줄인다.
  5. 주기 S마다 모든 프로세스를 Q0로 승급(부스트)해 기아를 막는다.
- **비유**: 우선순위는 손님의 '최근 회전율 점수'다. 자주 자리를 비우는(I/O) 손님은 점수가 유지돼 앞줄에, 계속 앉아 있는(CPU) 손님은 점수가 깎여 뒷줄로 간다. 다만 뒷줄도 S초마다 리셋해 굶기지 않는다.
- **구체 예시(강등 계산)**: Q0=10ms, Q1=20ms, Q2=40ms. 15ms 작업이 들어오면 Q0에서 10ms 쓰고 퀀텀 소진 → Q1로 강등, Q1에서 남은 5ms 실행 후 종료. 반대로 3ms마다 I/O를 하는 대화형 작업은 계속 Q0에 남아 즉시 응답을 받는다.
- **흔한 오해·주의점**: (1) MLQ와 MLFQ는 다르다 — MLQ는 큐 간 이동이 없는 정적 구조, MLFQ는 피드백으로 이동한다. (2) 어뷰징 위험 — 퀀텀 만료 직전 일부러 I/O를 흉내 내 강등을 피할 수 있다. 이를 막으려면 '1회 할당량'이 아니라 '해당 큐에서의 총 누적 실행 시간'을 강등 기준으로 삼는다.

## 연결 개념
- 프로세스 스케줄링(004): MLFQ가 극복한 고전 알고리즘(FCFS·SJF·RR)의 한계.
- 기아와 에이징(011): 하위 큐 무한 대기를 부스트로 해소하는 원리.
- CFS(006): 파라미터 튜닝 부담을 수학적 공평성으로 대체한 후속 스케줄러.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MLFQ는 프로세스의 CPU 사용 이력을 피드백으로 삼아 다단계 우선순위 큐 사이를 이동시키는 적응형 스케줄링 기법임.
> 2. **가치**: 실행 시간을 모른 채로도 I/O 바운드의 응답성과 CPU 바운드의 낮은 문맥 전환 오버헤드를 동시에 달성함(SJF 근사).
> 3. **판단 포인트**: 큐 개수·퀀텀·강등/부스트 조건 등 튜닝 파라미터가 성능을 좌우하고, 어뷰징 방지 규칙이 설계 완성도를 결정함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 동적 피드백 스케줄링 원리 이해 | 다단계 큐, 퀀텀 차등, 강등·승급 피드백 | MLQ(고정 큐)와 혼동해 피드백 누락 |
| 단일 스케줄러 한계 극복 확인 | CPU/I/O 바운드 동적 판별, 기아·에이징 | "우선순위가 변한다"는 추상 표현에 그침 |
| 설계 한계와 극복 방안 제시 | 어뷰징(게이밍), 누적 시간 기준 강등 | 동작 설명에서 멈추고 한계 미제시 |

> 요약: 단일 큐 한계를 다중 큐+피드백으로 극복했고, 어뷰징 방지·부스트로 공평성까지 확보한 범용 스케줄러임.

## Ⅰ. 개요 및 필요성

- 개요: 우선순위가 다른 여러 큐를 두고 실행 이력에 따라 큐 간 이동시키는 동적 스케줄링 기법임
- 위치: (004 스케줄링의 특정 알고리즘 심화) SJF를 실행 시간 예측 없이 근사하려는 시도임
- 필요성: 대화형(응답성)과 배치(처리량)가 섞인 환경에서 작업 특성별 퀀텀 차등 적용이 필수임

## Ⅱ. 구조 및 구성요소

선형 구조도 (우선순위 ↓ = 퀀텀 ↑):

    새 프로세스 -> Q0(퀀텀 10ms, 응답성)
                    | 퀀텀 소진 시 강등
                   Q1(퀀텀 20ms)
                    | 퀀텀 소진 시 강등
                   Q2(퀀텀 40ms, 처리량)
    (주기 S마다 전체를 Q0로 부스트: 기아 방지)

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 다중 큐 | 우선순위별로 분리된 여러 Ready 큐 | 하위 큐일수록 퀀텀을 길게 설정 |
| 강등 룰 | 퀀텀 소진 프로세스를 하위 큐로 하향 | CPU 바운드 식별 수단 |
| 승급 룰(부스트) | 주기 S마다 전체를 최상위 큐로 상향 | 기아 방지·에이징 구현 |
| 스케줄러 엔진 | 항상 최상위 비어있지 않은 큐부터 선택 | 선점형 기반 |

> 요약: 우선순위와 퀀텀 크기가 반비례하는 다중 큐에 강등·부스트 피드백을 결합한 구조임.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도:

    Q0 진입 -> CPU 할당·실행
      -> [분기1] 퀀텀 내 I/O -> 현재 큐 유지(I/O 바운드 판정)
      -> [분기2] 퀀텀 만료 -> 하위 큐로 강등(CPU 바운드 판정)
      -> [주기] S 경과 -> 전체를 Q0로 부스트

- 1단계 [진입]: 새 작업은 최상위 큐 Q0에 배치되어 가장 짧은 응답 시간을 보장받음
- 2단계 [강등]: 퀀텀을 모두 소진하면 CPU 바운드로 판정해 한 단계 아래 큐로 내림
- 3단계 [유지]: 퀀텀 내 I/O 요청 시 I/O 바운드로 판정해 현재 우선순위를 유지함
- 4단계 [부스트]: 임계 시간 S마다 전체를 Q0로 올려 하위 큐 기아를 방지함

> 요약: 행동 이력을 피드백으로 삼아 I/O 바운드는 올리고 CPU 바운드는 내리며 우선순위를 동적 조정함.

## Ⅳ. 특징

- 응답성 보장: 신규·대화형 작업이 항상 최상위 큐에서 즉시 실행돼 SJF에 근접한 응답성을 제공함
- 오버헤드 통제: 하위 큐일수록 퀀텀을 길게 줘 CPU 바운드의 문맥 전환 횟수를 줄임
- 파라미터 민감성: 큐 개수·퀀텀·부스트 주기 S가 전체 성능을 좌우하는 튜닝 대상임
- 어뷰징 취약성: 퀀텀 만료 직전 I/O 흉내로 강등을 회피할 수 있어 방어 규칙이 필수임

## Ⅴ. 심화 비교 및 적용 판단

같은 다단계 큐라도 피드백 유무로 성격이 갈리므로 상위 개념 MLQ와 대조함.

| 구분 | MLQ (고정 다단계 큐) | MLFQ (피드백 다단계 큐) |
|:---|:---|:---|
| 큐 간 이동 | 불가(생성 시 큐 고정) | 가능(실행 이력 피드백) |
| 우선순위 갱신 | 정적(변경 없음) | 동적(강등·부스트) |
| 기아 대응 | 별도 장치 필요 | 부스트(에이징) 내장 |
| 오버헤드 | 낮음(상태 감시 불필요) | 높음(이력 추적·큐 이동) |

> 요약: 작업 성격이 고정된 특수 시스템은 MLQ를, 성격이 변하는 범용 환경은 MLFQ를 적용함.

**리스크·대응:**
- 어뷰징(게이밍): 퀀텀 직전 I/O로 강등 회피 → 1회 할당이 아닌 '큐 내 총 누적 실행 시간' 기준 강등으로 규칙 변경
- 멀티코어 락 경합: 단일 공유 MLFQ에 코어들이 몰림 → 코어별 개별 런큐로 분산
- 부스트 주기 오설정: S가 크면 기아, 작으면 CPU 바운드가 밀림 → 하위 큐 대기 시간을 샘플링해 S 자동 조정

**점검 지표:**
- 성능: 대화형 작업 p95 응답 시간, 시스템 처리량
- 운영: 하위 큐 평균 대기 시간(기아 여부), 강등/부스트 발생 빈도

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 부하 연동 퀀텀 조정: Load Average를 모니터링해 평상시 짧은 퀀텀, 폭주 시 긴 퀀텀으로 오버헤드 방어
2. 부스트 임계값 S 튜닝: 하위 큐 대기 시간을 주기 샘플링해 기아 감지 시 S를 단축하여 승급 가속
3. 상위 실시간 큐 분리: 미디어 등 Soft Real-Time은 MLFQ 위 고정 큐로 분리해 지터 억제

**결론:**
- 기술사 판단: MLFQ는 범용 OS의 성능·공평성을 조율하는 핵심 기법이나, 파라미터 튜닝의 손이 많이 감
- 향후 방향: 이 튜닝 부담을 없애기 위해 리눅스는 vruntime으로 공평성을 수학적으로 보장하는 CFS로 진화함
