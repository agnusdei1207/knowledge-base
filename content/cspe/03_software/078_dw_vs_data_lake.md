## Ⅰ. 개요
- 기업의 의사결정을 지원하기 위해 데이터를 통합하고 저장하는 대규모 데이터 관리 체계임.
- 구조화된 분석 중심의 DW와 원시 데이터 중심의 Data Lake로 구분됨.
- 출제 의도: 데이터 특성 및 분석 목적에 따른 저장소 아키텍처 선정 역량 평가.

## Ⅱ. 구성요소
- DW vs Data Lake 비교
[Sources] -> [DW (Schema-on-Write)] / [Lake (Schema-on-Read)]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Data Warehouse | 정제된 정형 데이터 저장, OLAP 기반 분석 | 정수기 필터링 물 |
| Data Lake | 정형/비정형 원시 데이터 그대로 저장 | 호수 물 |
| Data Mart | 특정 부서/목적에 맞게 추출된 소규모 DW | 생수병 |
> 요약: 목적이 뚜렷한 가공 데이터(DW)와 잠재 가치가 큰 원본 데이터(Lake)의 차이임.

## Ⅲ. 절차
- 데이터 레이크하우스(Lakehouse) 아키텍처
[Raw Data] -> (Lake) -> (Metadata Layer) -> (DW Features) -> [Analysis]

1. 수집: 스트리밍, 배치 방식으로 모든 원시 데이터 레이크에 적재함.
2. 메타데이터 관리: 스키마 정보와 카탈로그를 부여하여 검색 가능케 함.
3. 거버넌스 적용: 접근 제어, 무결성 제약 등 DW의 관리 기능을 결합함.
4. 분석 실행: SQL 및 ML 툴을 통해 통합된 환경에서 데이터 탐색함.
> 요약: 레이크의 유연성과 DW의 관리성을 결합하여 통합 플랫폼을 구축함.

## Ⅳ. 문제점
- 데이터 레이크 내 방치된 데이터로 인한 데이터 늪(Data Swamp) 발생 위험.

## Ⅴ. 개선방안
- 엄격한 데이터 카탈로그 관리 및 라이프사이클 기반의 자동 삭제 정책 수립.

## Ⅵ. 전망
- AI 분석에 최적화된 Vector DB 기능을 포함한 통합 데이터 플랫폼으로 진화.
- 클라우드 네이티브 환경의 비용 효율적인 서버리스 분석 엔진 도입 확대.
