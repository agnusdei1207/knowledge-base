## Ⅰ. 개요
- 정의: 트랜잭션 내의 모든 Lock 연산이 Unlock 연산보다 먼저 수행되도록 하는 직렬성 보장 프로토콜
- 배경: 병행 제어 시 트랜잭션의 직렬 가능성(Serializability)을 이론적으로 보장 필요
| 구분 | 내용 |
|------|------|
| 출제 의도 | 확장 단계(Growing)와 수축 단계(Shrinking)의 구분 및 특징 파악 |

## Ⅱ. 구성요소
  # Locks ^  /----(Growing)----\ (Lock Point)
          | /                  \----(Shrinking)----
          +-------------------------------------> Time
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| Growing Phase | 새로운 락만 획득 가능하고 해제는 불가한 단계 | 쇼핑 시간 |
| Shrinking Phase | 획득한 락을 해제만 가능하고 획득은 불가한 단계 | 짐 정리 시간 |
| Lock Point | 트랜잭션이 마지막 락을 획득한 시점 | 장바구니 피크 |
> 요약: 락의 획득과 해제 시점을 엄격히 분리하여 일관성 보장

## Ⅲ. 절차
  Acquire Lock A -> Acquire Lock B -> (Lock Point) -> Release A -> Release B
1. Growing: 데이터 접근 시 필요한 모든 락을 순차적으로 획득
2. Execution: 획득한 락을 보유한 채 실제 데이터 연산 수행
3. Shrinking: 연산 완료 후 더 이상 필요 없는 락부터 차례로 해제
4. Completion: 모든 락을 반납하고 트랜잭션 종료
> 요약: 단계별 락 관리로 데이터 충돌 방지 및 직렬 스케줄 형성

## Ⅳ. 문제점
- 직렬성은 보장하나 교착 상태(Deadlock) 발생을 예방하지 못함
- 트랜잭션이 락을 오래 보유하여 동시성 및 응답 속도 저하

## Ⅴ. 개선방안
- Strict 2PL(커밋 시점에 일괄 해제) 적용으로 연쇄 복구 방지
- Deadlock 탐지 알고리즘 및 타임아웃 기법 병행 운영

## Ⅵ. 전망
- 락 프리(Lock-free) 자료 구조 및 분산 환경의 타임스탬프 기반 순서 보정 기술로 진화
