## Ⅰ. 개요
- **정의**: AI 모델을 핵심 로직으로 내장하여 설계 단계부터 AI 중심으로 구축된 애플리케이션
- **배경/필요성**: 기존 앱에 AI를 사후 부착하면 아키텍처 불일치로 성능·유지보수에 한계가 발생함
- **비유**: 전기차가 엔진이 아닌 모터 중심으로 차체를 설계하듯, AI를 핵심 축으로 앱을 설계하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 기반 앱 아키텍처 이해 | AI-Native vs AI-Enabled 차이 | 파이프라인 설계 관점 서술 |

> 요약: AI 네이티브 앱은 AI를 보조 기능이 아닌 핵심 아키텍처로 내장한 애플리케이션임

## Ⅱ. 구성요소
```text
[User Input] --요청--> [AI Orchestrator]
                            |
              +-------------+-------------+
              |             |             |
              v             v             v
        [LLM/Model]   [Vector Store]  [Tool/API]
              |             |             |
              v             v             v
        [Inference]   [RAG Retrieval] [Action Exec]
              |             |             |
              +------+------+------+------+
                     |
                     v
              [Response Composer]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| AI Orchestrator | 사용자 요청을 분석하여 모델·도구 호출 순서를 결정함 | 오케스트라 지휘자 |
| Vector Store | 도메인 지식을 벡터로 저장하여 RAG 검색을 지원함 | 전문 참고 자료실 |
| Tool/API | 외부 서비스·DB와 연동하여 AI 판단을 실행으로 전환함 | 도구를 사용하는 손 |

> 요약: 오케스트레이터가 모델·벡터·도구를 조합하여 AI 중심 응답을 생성함

## Ⅲ. 절차
```text
요청 수신 --> 의도 분석 --> 추론/검색 --> 응답 합성
    |             |             |             |
    v             v             v             v
  입력정제     라우팅결정    모델+RAG      결과조합
```
- 1단계: 사용자 입력을 정제하고 컨텍스트를 구성함
- 2단계: 오케스트레이터가 의도를 분석하여 모델·도구 호출 계획을 수립함
- 3단계: LLM 추론과 RAG 검색을 병행하여 근거 기반 결과를 생성함
- 4단계: 추론 결과와 도구 실행 결과를 합성하여 최종 응답을 반환함

> 요약: 수신-분석-추론-합성 4단계로 AI 중심 요청 처리를 수행함

## Ⅳ. 문제점
- 추론 비용 급증: 요청마다 LLM 호출이 발생함 — 트래픽 증가 시 비용이 선형 이상으로 증가함
- 비결정적 출력: 동일 입력에 상이한 응답이 생성됨 — 테스트·디버깅이 곤란함
- 모델 의존 장애: 외부 모델 API 장애가 전체 앱 장애로 전파됨 — 가용성이 저하됨

> 요약: 비용 급증·비결정성·모델 의존이 AI 네이티브 앱의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 시맨틱 캐싱으로 유사 질의 재호출을 방지하여 비용을 절감
2. 중기: 결정적 출력이 필요한 경로에 시드 고정·규칙 기반 후처리를 적용
3. 장기: 멀티 모델 폴백(Fallback) 아키텍처로 단일 모델 장애를 격리

> 요약: 캐싱-결정성 확보-폴백 설계 순으로 운영 안정성을 확보할 필요

## Ⅵ. 전망
- 발전 방향: 멀티 에이전트 협업 기반의 자율형 AI 앱으로 진화함
- 기술사적 판단: AI 네이티브 패턴이 차세대 앱 아키텍처의 기본 템플릿이 될 것임
- 기술사 제언: AI 파이프라인 설계 패턴과 비용 최적화 전략을 아키텍처 표준에 포함할 필요
