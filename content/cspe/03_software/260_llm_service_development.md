# 📖 【암기용】 개념 완전 이해

> 목적: LLM 기반 서비스 개발과 RAG 구현을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: RAG 구현은 외부 문서를 검색해 LLM 프롬프트에 넣고 근거 기반 답변을 생성하는 LLM 서비스 개발 방식이다.
- **왜 필요한가**: LLM은 학습 이후 생긴 사내 문서와 업무 규정을 모를 수 있고, 근거 없는 답변을 만들 수 있다. 검색 결과를 붙이면 문서 기반 답변을 만들 수 있다.
- **핵심 직관**: LLM에게 기억만 믿고 답하라 하지 않고, 시험 직전에 관련 교재 페이지를 찾아 건네준 뒤 답하게 하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 기업 서비스는 사내 규정, 계약서, 매뉴얼처럼 자주 바뀌는 문서를 답변 근거로 써야 한다. 매번 파인튜닝하면 비용과 갱신 시간이 커진다.
- **작동 원리**: 문서를 수집해 청크로 나누고 임베딩을 생성해 벡터 DB에 저장한다. 질문이 오면 관련 청크를 검색해 프롬프트에 넣고 LLM이 답변한다.
- **비유**: 상담원이 모든 규정을 외우는 대신 검색 시스템에서 관련 조항을 찾아 읽고 답변하는 절차와 같다.
- **구체 예시**: 사내 헬프데스크는 Confluence 문서를 500토큰 청크로 분할하고 top-k 5개 문서를 검색해 답변과 출처 URL을 반환한다.
- **흔한 오해·주의점**: RAG는 환각을 0으로 만들지 않는다. 문서 품질, 청크 크기, 검색 방식, 권한 필터링, 답변 평가가 함께 필요하다.

## 연결 개념
- Vector DB: 임베딩 벡터 저장과 유사도 검색
- Hybrid Search: BM25와 벡터 검색 결합
- LLMOps: 프롬프트, 평가, 비용, 안전 운영

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: RAG 구현 답안은 문서 수집, 청크, 임베딩, 검색, 프롬프트 보강, 평가, 권한 필터링을 흐름으로 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RAG는 외부 지식 검색 결과를 LLM 입력 컨텍스트에 결합해 근거 기반 답변을 생성하는 아키텍처다.
> 2. **가치**: 모델 재학습 없이 문서 갱신을 반영하고 답변 출처를 제공해 업무 적용 가능성을 높인다.
> 3. **판단 포인트**: 검색 품질, 권한 필터링, 청크 설계, 환각 평가, 토큰 비용을 함께 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| RAG 구조 이해 | 문서 적재, chunking, embedding, vector DB, retrieval | LLM API 호출만 설명 |
| 서비스 설계 판단 | 권한 필터, 출처 표시, 평가셋, 캐시 | 환각이 완전 제거된다고 표현 |
| 운영 리스크 확인 | 개인정보, 문서 품질, 검색 실패, 비용 | 보안과 평가 지표 누락 |

> 요약: RAG 문제는 LLM 모델보다 데이터 파이프라인과 검색 품질 설계를 평가한다.

---

## Ⅰ. 개요 및 필요성

RAG는 검색 결합 LLM 서비스 구조다. 사내 문서와 업무 지식은 자주 바뀌므로 모델 재학습만으로 대응하기 어렵다. 문서 검색 결과를 프롬프트에 결합해 근거 문서 기반 답변을 생성한다.

---

## Ⅱ. 구조 및 구성요소

```text
Document -> Chunking -> Embedding -> Vector DB
Query -> Retriever -> Prompt Augmentation -> LLM -> Answer with Source
                    / Access Filter
                    / Evaluation
```

| 구성요소 | 역할 | 설계 기준 |
|:---|:---|:---|
| 문서 파이프라인 | 수집, 정제, 청크 분할 | 300~800토큰 청크 |
| 임베딩·벡터 DB | 문서 벡터화와 유사도 검색 | top-k, cosine, HNSW |
| Retriever | 질의와 관련 문서 선택 | hybrid search, rerank |
| Generator | 검색 문서를 근거로 답변 생성 | 출처 표시, 금칙어 필터 |

> 요약: RAG는 문서 인덱싱 경로와 질의 응답 경로를 분리해 검색 결과를 LLM 입력으로 제공한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
문서 수집 -> 청크 분할 -> 임베딩 저장 -> 질문 임베딩 -> top-k 검색 -> 프롬프트 보강 -> 답변 생성 -> 평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서 수집과 청크 분할 | 중복 제거, 권한 태그 |
| 2 | 임베딩 생성과 벡터 인덱스 구축 | 검색 recall@k |
| 3 | 질의 검색과 rerank 수행 | MRR, nDCG |
| 4 | 근거 포함 답변 생성과 평가 | faithfulness, answer relevancy |

> 요약: RAG 품질은 LLM보다 문서 청크, 검색 recall, 근거 일치 평가에 의해 크게 좌우된다.

## Ⅳ. 특징

| 구분 | 파인튜닝 | RAG 구현 | 판단 포인트 |
|:---|:---|:---|:---|
| 목적 | 모델 행동과 형식 학습 | 외부 지식 근거 제공 | 지식 갱신 주기 |
| 갱신 방식 | 재학습 필요 | 문서 재색인 | 문서 변경 빈도 |
| 리스크 | 학습 비용, 데이터 준비 | 검색 실패, 권한 누락 | 평가셋과 필터 |

> 요약: RAG는 지식 갱신과 근거 표시가 필요한 서비스에 적합하고, 형식·스타일 학습은 파인튜닝이 적합하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | RAG 구현 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | LLM 단독 호출 | 검색+프롬프트 보강 | 사내 문서 기반 답변 |
| 비용/성능 | 프롬프트 짧음 | 검색 지연과 토큰 증가 | p95 3초 목표 |
| 운영/위험 | 근거 부족 | 출처와 권한 필터 | 감사·고객 응답 |

> 요약: 사내 지식과 근거 제시가 필요하면 RAG를 선택하고, 단순 요약·분류는 LLM 단독 호출도 가능하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 검색 실패 | 청크 품질, 임베딩 부적합 | hybrid search, reranker | recall@5, MRR |
| 권한 위반 | 문서 ACL 미반영 | metadata filter, ABAC | 권한 위반 0건 |
| 환각 답변 | 근거 외 생성 | 출처 필수, answer grounding 평가 | faithfulness 95% |

> 요약: RAG 리스크는 검색 실패, 권한 위반, 환각이며 검색 평가와 권한 필터로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검색 품질 | recall@5 90%, MRR 기준 충족 | 골든셋 평가 |
| 답변 품질 | faithfulness 95%, 출처 포함률 100% | RAGAS, Human Review |
| 서비스 지표 | p95 3초, 요청당 비용 예산 준수 | LLM Gateway, APM |

> 요약: RAG 운영 평가는 검색 품질, 근거 일치, 지연·비용을 함께 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Confluence, PDF, DB 문서를 수집해 300~800토큰 청크로 분할하고 문서 ACL과 출처 URL을 metadata로 저장함
2. OpenSearch BM25와 Vector DB HNSW를 결합한 hybrid search 후 reranker로 top-k 5개 문서를 선별함
3. RAGAS 또는 자체 골든셋으로 recall@5 90%, faithfulness 95%, p95 3초 기준을 배포 게이트로 설정함

**결론 (2줄):**
- 기술사 판단: 지식 갱신과 출처 제시가 필요한 업무는 RAG를 우선 적용하고, 응답 형식 고정이 핵심이면 파인튜닝을 병행함
- 향후 방향: RAG는 multi-hop retrieval, agentic workflow, 권한 기반 검색과 결합해 기업 지식 서비스의 기본 구조로 발전함
