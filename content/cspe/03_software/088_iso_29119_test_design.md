## 미리 알고가기

- ISO/IEC/IEEE 29119는 소프트웨어 테스트 프로세스와 문서와 기법을 다루는 국제 표준임
- 테스트 조건은 무엇을 검증해야 하는지 정리한 항목임
- 종료 기준은 어느 수준까지 검증했을 때 테스트를 끝낼지 정한 기준임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- ISO 29119 테스트 설계는 요구·위험, 테스트 조건, 케이스·절차, 종료 기준을 핵심 축으로 설명함
- 비교표는 비형식 설계와 표준 기반 설계의 범위 근거·산출물·추적성·적용 조건을 대비함
- 금융 거래 테스트와 제품팀 문서 갱신은 요구 추적률·낡은 절차 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: ISO 29119 테스트 설계는 요구·위험에서 테스트 조건을 도출하고 케이스·절차·커버리지·종료 기준으로 구체화하는 표준 기반 방식임
- **배경/필요성**: 테스트 누락·중복과 문서 불일치를 줄이기 위해 범위·추적 관계·종료 조건을 관리하는 설계 기준이 필요함

## Ⅱ. 특징

- 요구사항과 위험을 기준으로 테스트 범위를 구조화함
- 테스트 조건과 케이스와 절차를 분리해 재사용성과 추적성을 높임
- 커버리지와 종료 기준을 명시해 품질 판단 기준을 분명히 함
- 문서 수준이 과도하면 변화가 빠른 프로젝트에서 유지 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 비형식 테스트 설계 | ISO 29119 기반 설계 |
|:---|:---|:---|
| 범위 정의 | 개인 경험과 팀 관행으로 시나리오 선택 | 요구사항·위험·테스트 조건으로 범위 정의 |
| 산출물 | 자유 형식 테스트 목록·실행 결과 | 테스트 조건·케이스·절차·결과·추적 관계 |
| 주요 한계 | 핵심 시나리오 누락과 중복이 생기기 쉬움 | 문서와 갱신 규칙을 함께 관리해야 함 |
| 활용 범위 | 소규모·단기 검증 | 규제 산업·대형 반복 검증·감사 대응 |

> 요약: 비형식 설계는 팀 관행으로 범위를 정하고, ISO 29119 기반 설계는 요구·위험·추적 관계로 범위를 통제함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 테스트 조건 | 검증해야 할 기능과 규칙과 위험 지점을 정의함 |
| 테스트 케이스 | 입력과 기대 결과를 명시해 실행 가능한 검증 단위를 만듦 |
| 테스트 절차 | 케이스 실행 순서와 환경과 준비 조건을 적어 재현성을 높임 |
| 커버리지와 종료 기준 | 어느 수준까지 검증했는지와 언제 종료할지 판단하게 함 |

> 요약: 테스트 조건을 입력·기대 결과·실행 절차로 구체화하고 커버리지·종료 기준으로 범위를 통제함.

## Ⅴ. 원리 및 절차 흐름도

1. **범위와 위험 정의**: 요구사항과 결함 위험과 품질 속성을 정리함
2. **조건 도출**: 경계와 예외와 업무 규칙을 테스트 조건으로 추출함
3. **케이스와 절차 설계**: 입력과 기대 결과와 실행 순서를 문서화함
4. **커버리지 검토**: 추적성과 종료 기준 충족 여부를 확인함

> 요약: 요구·위험에서 테스트 조건을 도출해 케이스와 절차로 구체화하고 커버리지·종료 기준을 검토함.

## Ⅵ. 실무 사례

1. 금융 거래 플랫폼은 요구-테스트 추적 행렬을 운영하고 요구 추적률·미연결 테스트 건수를 확인함
2. SaaS 제품팀은 요구 변경 시 테스트 절차 갱신을 자동화하고 문서 최신성·만료 절차 비율을 확인함

## Ⅶ. 결론

- ISO 29119 테스트 설계는 요구·위험을 테스트 조건·케이스·종료 기준으로 추적함
