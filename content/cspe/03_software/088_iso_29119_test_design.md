## 미리 알고가기

- ISO/IEC/IEEE 29119는 소프트웨어 테스트 프로세스와 문서와 기법을 다루는 국제 표준임
- 테스트 설계는 요구사항과 위험을 실행 가능한 테스트 조건과 케이스로 변환하는 활동임
- 기법 선택은 기능 특성과 위험 수준과 변경 빈도에 따라 달라짐

## Ⅰ. 개요

- **정의/개념**: ISO 29119 테스트 설계는 요구사항과 위험과 품질 목표를 기준으로 테스트 조건과 케이스와 절차와 커버리지 기준을 체계적으로 정의해 반복 가능하고 추적 가능한 검증 활동으로 만드는 표준 기반 설계 방식임
- **배경/필요성**: 테스트를 경험과 감에만 의존하면 누락과 중복과 문서 불일치가 커지므로, 설계 근거와 범위와 종료 기준을 일관되게 관리할 기준이 필요함

## Ⅱ. 특징

- 요구사항과 리스크 기반으로 테스트 범위를 구조화함
- 테스트 조건과 케이스와 절차를 분리해 재사용성과 추적성을 높임
- 커버리지와 종료 기준을 명시해 품질 판단 기준을 분명히 함
- 문서 수준이 과도하면 변화가 빠른 프로젝트에서 유지 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 비형식 테스트 설계 | ISO 29119 기반 설계 |
|:---|:---|:---|
| 범위 정의 | 개인 경험 중심 | 요구사항과 위험 기준 |
| 추적성 | 낮음 | 높음 |
| 변경 대응 | 빠르지만 누락 가능 | 절차적이나 통제 용이 |
| 적합 환경 | 소규모 단기 검증 | 규제·대형·반복 검증 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Test Condition | 검증해야 할 기능과 규칙과 위험 지점을 정의해 설계 기준을 세움 |
| Test Case | 입력과 예상 결과를 명시해 실행 가능한 검증 단위로 만듦 |
| Test Procedure | 케이스 실행 순서와 환경과 준비 조건을 명시해 재현성을 높임 |
| Coverage and Exit Criteria | 어느 수준까지 검증했는지와 언제 종료할지 판단 기준을 제공함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 범위/위험 정의 | --> | 조건 도출      | --> | 케이스/절차 설계 | --> | 커버리지 검토  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **범위와 위험 정의**: 요구사항과 결함 위험과 품질 속성을 정리함
2. **조건 도출**: 경계와 예외와 업무 규칙을 테스트 조건으로 추출함
3. **케이스와 절차 설계**: 입력과 기대 결과와 실행 순서를 문서화함
4. **커버리지 검토**: 추적성과 종료 기준 충족 여부를 확인함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 요구사항과 테스트 조건 연결이 약하면 문서가 있어도 핵심 시나리오 누락이 발생할 수 있음
   - 해결방안: requirement-to-test trace matrix를 운영하고 trace completeness와 uncovered requirement count로 검증함
2. 문제: 모든 케이스를 동일한 깊이로 설계하면 고위험 영역과 저위험 영역의 투자 균형이 무너질 수 있음
   - 해결방안: risk-based prioritization을 적용하고 high-risk coverage ratio와 design effort efficiency로 검증함
3. 문제: 문서 갱신이 개발 변경 속도를 따라가지 못하면 테스트 절차가 빠르게 진부화될 수 있음
   - 해결방안: change-triggered review를 자동화하고 test artifact freshness와 stale procedure ratio로 검증함

## Ⅶ. 적용 사례

- 금융 거래 시스템 테스트 설계에서는 추적 행렬을 운영하고 확인 지표는 trace completeness와 uncovered requirement count임
- 의료기기 소프트웨어 검증에서는 위험 기반 우선순위를 적용하고 확인 지표는 high-risk coverage ratio와 design effort efficiency임
- CI 기반 제품팀에서는 변경 연동 갱신을 자동화하고 확인 지표는 test artifact freshness와 stale procedure ratio임

## Ⅷ. 결론

ISO 29119 테스트 설계의 핵심은 테스트 양을 늘리는 것이 아니라 요구사항과 위험과 커버리지 기준을 구조화해 검증 누락을 줄이는 데 있음.
