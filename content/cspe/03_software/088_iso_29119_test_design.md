# 📖 【암기용】 개념 완전 이해

> 목적: ISO 29119를 테스트 프로세스와 설계기법의 국제 표준 체계로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: ISO/IEC/IEEE 29119는 **소프트웨어 테스트 프로세스**와 **테스트 설계기법**을 정의한 국제표준이다 — 조직마다 다른 테스트 방식을 정책·계획·설계·실행·종료 기준까지 하나의 절차로 통일한다.
- **왜 필요한가**: 테스트가 개인 경험에 의존하면 같은 기능도 담당자마다 다른 케이스를 만들어 무엇을 놓쳤는지 알 수 없고, "테스트를 언제 끝내도 되는가"를 판단할 근거도 없다.
- **핵심 직관**: 테스트를 감이 아니라 "요구사항 → 설계기법으로 케이스 도출 → 실행 → 커버리지로 종료 판정"이라는 재현 가능한 공정으로 만드는 표준이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 테스트 프로세스 | 계획-설계-실행-종료로 이어지는 테스트 절차 체계 — 이 표준이 규정하는 대상 | 검사 공정 전체 |
| 테스트 설계기법 | 요구사항에서 테스트 케이스를 뽑아내는 방법론(EP·BVA·DT·State) | 문제 출제 방법 |
| Test Policy/Strategy | 조직 차원의 테스트 원칙·방향(조직 테스트 프로세스) | 학교의 평가 방침 |
| Test Management | 계획 수립, 일정·위험 관리, 모니터링(테스트 관리 프로세스) | 시험 일정·감독 운영 |
| Dynamic Test Process | 설계-구현-실행-완료로 이어지는 실제 테스트 수행 절차 | 실제 시험 치르기 |
| 동등분할(EP, Equivalence Partitioning) | 입력값을 유효/무효 그룹으로 나눠 그룹당 대표값 하나만 테스트 | 반 편성 후 반장만 확인 |
| 경계값분석(BVA, Boundary Value Analysis) | 그룹의 경계(최소-1, 최소, 최대, 최대+1)를 집중 테스트 | 문턱 앞뒤를 밟아보기 |
| 결정테이블(Decision Table) | 여러 조건의 조합별 결과를 표로 만들어 빠짐없이 테스트 | 조건 곱셈표 |
| 상태전이(State Transition) | 상태와 이벤트에 따라 어떤 상태로 바뀌는지를 테스트 | 신호등 상태도(빨강→초록→노랑) |
| Coverage(커버리지) | 요구사항·코드가 테스트로 얼마나 확인됐는지 비율 | 시험범위 중 실제로 공부한 비율 |
| RTM(Requirement Traceability Matrix) | 요구사항-테스트조건-테스트케이스-결함을 잇는 추적표 | 요구사항별 출제 이력표 |
| 종료 기준(Exit Criteria) | 테스트를 끝내도 되는 정량 기준(커버리지·결함 등급) | 합격선 |

## 깊이 이해

### 왜 표준이 필요했나 (배경)
- ISO/IEC/IEEE 29119는 2013년부터 파트별로 공표된 국제표준으로, 그 전까지 조직마다 쓰던 IEEE 829(테스트 문서) 등 서로 다른 관행을 테스트 프로세스·문서·설계기법으로 통합했다.
- 문제의식은 단순하다. 같은 로그인 기능도 담당자 A는 정상 케이스 위주로, 담당자 B는 예외 케이스 위주로 짜면 결함이 특정 영역에 몰려 발견되지 않는다. 표준화된 설계기법 없이는 "무엇을 테스트했고 무엇을 안 했는지"조차 설명할 수 없다.

### 3단계 프로세스 구조
- **조직 테스트 프로세스**: 회사·사업부 차원에서 "우리는 이런 원칙으로 테스트한다"를 정하는 최상위 정책이다.
- **테스트 관리 프로세스**: 프로젝트 단위로 테스트 계획을 세우고 진행률·위험을 관리한다.
- **동적 테스트 프로세스**: 실제로 테스트 조건→케이스→절차를 설계하고 실행해 결과를 기록하는 실무 단계다. 여기서 설계기법이 쓰인다.

### 설계기법을 수치로 이해하기 — 비밀번호 8~20자 규칙
- **동등분할(EP)**: 입력을 "유효(8~20자)", "무효-짧음(<8자)", "무효-긺(>20자)" 3개 그룹으로 나눈다. 8~20자 사이의 13가지 길이를 전수 테스트할 필요 없이 그룹당 대표값 1개씩, 총 3케이스로 압축한다.
- **경계값분석(BVA)**: 그룹의 경계에서 결함이 가장 잘 나므로 7자(무효), 8자(유효 최소), 20자(유효 최대), 21자(무효) 4개 값을 테스트한다. `<=` 를 `<`로 잘못 짠 실수(off-by-one)는 이 4개 경계값에서만 드러난다.
- **결정테이블**: 조건이 여러 개 얽히면 표로 정리한다. 예: 계정상태(활성/잠금) × 인증수단(비밀번호/OTP) 2개 조건 × 2개 값이면 2²=4개 규칙(활성+비밀번호, 활성+OTP, 잠금+비밀번호, 잠금+OTP)이 나온다. 조건이 3개로 늘면 2³=8개로 조합이 기하급수적으로 늘어나므로, 결정테이블은 이 조합을 빠짐없이 표로 강제한다.
- **상태전이**: 계정 상태가 "활성→잠금(로그인 5회 실패)→활성(관리자 해제)"처럼 이벤트에 따라 바뀌는 흐름을 상태도로 그리고, 상태마다·전이마다 케이스를 만든다. 정의되지 않은 전이(예: "잠금" 상태에서 "탈퇴" 이벤트가 뭘 해야 하는지)를 찾아내는 데 특히 유용하다.

### Coverage와 종료 기준
- 요구사항이 100건인데 설계된 테스트 조건이 95건까지 매핑됐다면 requirement coverage는 95%다. 종료 기준을 "coverage 95% 이상, 치명 결함 0건"처럼 숫자로 정해두면 "감으로 그만하자"가 아니라 데이터로 종료를 결정할 수 있다.
- RTM은 요구사항 → 테스트조건 → 테스트케이스 → 발견된 결함을 한 줄로 연결한 표라서, 이 coverage 계산과 "이 요구사항은 어떤 케이스로 검증됐는가" 추적의 근거가 된다.

### 비유와 흔한 오해
- **비유**: 병원 건강검진이 의사 재량에만 맡겨지면 안 되므로, 검사 항목·절차·판정 기준(정상/경계/이상)을 표준화하는 것과 같다. 동등분할·경계값분석은 "이 항목은 어떤 수치대를 봐야 이상인지"를 정하는 것에 해당한다.
- **오해**: ISO 29119는 테스트 케이스 문서 양식만 정한 게 아니다. 조직 정책(Test Policy)부터 관리(Management), 실제 설계기법, coverage 기반 종료까지 전 과정을 포함한다. 설계기법 하나만 배워서 "표준 준수"라고 말할 수 없다.

## 연결 개념
- Test Coverage — 테스트 충분성을 수치로 표현하는 지표(이 표준의 종료 기준에 직결)
- V-model — 개발 산출물 단계별로 어떤 테스트를 대응시킬지 정하는 모델
- SP 인증 — 테스트 프로세스를 포함한 SW 프로세스 전체 품질을 심사하는 상위 제도

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: ISO 29119 답안은 표준 구성, 테스트 설계기법, 산출물, coverage 기반 종료 기준을 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO 29119는 SW 테스트를 조직 프로세스, 관리 프로세스, 동적 테스트 프로세스, 설계기법으로 표준화한 국제 표준이다.
> 2. **가치**: 테스트 계획·설계·구현·실행·완료 기준을 통일해 결함 누락과 재현 실패를 줄인다.
> 3. **판단 포인트**: 요구사항 위험도에 맞는 설계기법과 coverage 목표를 선택하고 종료 기준을 수치로 제시해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 테스트 표준 이해 확인 | ISO 29119 프로세스·문서·기법 | 단순 테스트 종류 나열로 끝내지 않음 |
| 설계기법 적용 역량 확인 | 동등분할, 경계값, 결정테이블, 상태전이 | 모든 기능에 같은 기법을 적용하지 않음 |
| 품질 지표 판단 확인 | coverage, 결함밀도, 종료 기준 | 테스트 건수만으로 충분성을 판단하지 않음 |
> 요약: 이 문제는 테스트를 표준 프로세스와 설계기법, 수치 종료 기준으로 관리하는 역량을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: SW 테스트 국제 표준
- 배경: 테스트가 개인 경험에 의존하면 요구 누락, 중복 케이스, 결함 재현 실패, 종료 기준 불명확 문제가 발생한다.
- 필요성: ISO/IEC/IEEE 29119는 테스트 프로세스, 문서, 기법을 표준화해 위험도 기반 테스트 설계와 coverage 목표를 검수 근거로 연결한다.

---

## Ⅱ. 구조 및 구성요소

```text
Test Policy/Strategy -> Test Management -> Dynamic Test Process
-> Test Design Techniques -> Test Case/Procedure
-> Execution Result -> Completion Report
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| 조직 테스트 프로세스 | 정책·전략·개선 관리 | 테스트 표준과 역할 |
| 테스트 관리 프로세스 | 계획·모니터링·통제 | 일정, 위험, 종료 기준 |
| 동적 테스트 프로세스 | 설계·구현·실행·완료 | 케이스, 절차, 결과 |
| 설계기법 | 테스트 조건 도출 | EP, BVA, DT, State |
> 요약: ISO 29119는 조직 정책부터 테스트 설계와 실행 결과 보고까지 전 과정을 표준화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 분석 -> 위험도 평가 -> 테스트 조건 도출
-> 설계기법 선택 -> 테스트 케이스 작성 -> 실행
-> 결함 기록 -> coverage/종료 기준 평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 테스트 대상과 요구사항 분석 | 요구사항 매핑 100% |
| 2 | 위험도 기반 우선순위 부여 | 중요 기능 P1 식별 |
| 3 | 설계기법으로 케이스 도출 | EP/BVA/DT/State 적용 근거 |
| 4 | 테스트 실행과 결함 기록 | 결함 재현 정보 100% |
| 5 | 종료 기준 평가 | 요구 coverage 95% 이상 |
> 요약: ISO 29119 테스트는 요구사항에서 테스트 조건을 도출하고 coverage와 결함 상태로 종료를 판단한다.

## Ⅳ. 특징

| 구분 | 비표준 테스트 | ISO 29119 테스트 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 프로세스 | 담당자별 상이 | 계획·설계·실행·완료 표준 | 단계별 산출물 |
| 설계 | 경험 기반 케이스 | EP·BVA·결정테이블 등 | 요구사항 coverage 95% |
| 종료 | 일정 기준 종료 | 결함 상태·coverage 기준 | 치명 결함 0건 |
| 한계 | 문서 부담 적음 | 표준 적용 공수 필요 | 위험 기반 Tailoring |
> 요약: ISO 29119는 테스트 재현성과 검수 근거를 제공하지만 위험도에 따른 Tailoring이 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 애드혹 테스트 | 표준 프로세스 기반 테스트 | 감리·감사·협력사 참여 |
| 비용/규모 | 초기 문서 공수 낮음 | 설계·증적 공수 증가 | 결함 비용 높은 시스템 |
| 운영/위험 | 누락·중복 발견 지연 | coverage 기반 통제 | 요구사항 100건 이상 |
| 품질 | 결함 건수 중심 | 위험도·coverage·종료 기준 | 검수 기준 명확화 필요 |
> 요약: ISO 29119는 결함 비용이 높은 프로젝트에서 테스트 충분성과 검수 기준을 수치화하는 데 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문서 과다 | 모든 항목 동일 적용 | 위험 기반 Tailoring | 산출물 생략 승인율 |
| 케이스 누락 | 설계기법 선택 오류 | 요구사항별 기법 매핑 | requirement coverage |
| 결함 재현 실패 | 로그·환경 정보 부족 | 결함 템플릿 표준화 | 재오픈율 5% 이하 |
| 종료 논쟁 | 종료 기준 불명확 | coverage·결함 등급 기준 합의 | 종료 승인 지연 0건 |
> 요약: 테스트 표준 적용 리스크는 Tailoring, 기법 매핑, 결함 기록, 종료 기준 합의로 줄인다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 요구 coverage | 95% 이상 | RTM 추적 |
| 결함 품질 | 재오픈율 5% 이하 | 결함관리 도구 |
| 설계기법 적용 | 주요 기능 100% 매핑 | 테스트 설계 리뷰 |
| 종료 기준 | 치명 결함 0건 | 테스트 완료 보고서 |
> 요약: ISO 29119 효과는 coverage, 재오픈율, 설계기법 매핑, 종료 기준 충족으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 요구사항 위험도에 따라 P1 기능은 경계값·결정테이블·상태전이를 필수 적용하고 P3 기능은 체크리스트 테스트로 Tailoring함.
2. 요구사항-테스트조건-테스트케이스-결함을 RTM으로 연결하고 coverage 95% 이상을 종료 기준으로 설정함.
3. 테스트 완료 보고서에 미해결 결함, 우회방안, 잔여위험 승인자를 포함해 검수 기준을 명확히 함.

**결론 (2줄):**
- 기술사 판단: 감리·검수·협력사 연계가 있는 프로젝트는 ISO 29119 기반 프로세스를 적용하고, 소규모 제품팀은 위험 기반 Tailoring을 병행함.
- 향후 방향: 테스트 표준은 CI/CD, 테스트 자동화, 품질 대시보드와 결합해 지속 검증 체계로 발전함.
