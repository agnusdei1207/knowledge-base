## 미리 알고가기

- 분산 데이터베이스는 여러 노드의 분할·복제 데이터를 하나의 논리 데이터베이스로 제공하는 구조임
- 파티셔닝은 서로 다른 데이터를 나누고 복제는 같은 데이터의 사본을 여러 장애 영역에 배치함
- 분산 투명성은 데이터 위치·분할·복제 세부를 응용 질의에서 숨기는 성질임
- 2단계 커밋은 참여 노드의 커밋·중단을 원자적으로 결정하고 합의 프로토콜은 복제 로그의 리더·순서를 일치시킴
- 정족수(Quorum)는 읽기·쓰기 완료에 필요한 복제본 응답 수를 뜻함

## 작성 근거(검토용)

- 분산 DB는 분할·복제·라우팅·일관성·분산 트랜잭션·복구를 핵심 판단축으로 설명함
- 비교표는 단일·분산 DB의 데이터 배치·확장 방식·트랜잭션 및 일관성을 대비함
- 실무 사례는 테넌트 샤딩과 트랜잭션 경계를 부하 편차·재분산 시간·교차 샤드 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: 분산 데이터베이스는 데이터를 여러 노드에 분할·복제하고 라우팅·분산 질의·일관성·트랜잭션·복구를 통합해 하나의 논리 DB로 제공하는 구조임
- **배경/필요성**: 단일 노드의 저장·처리 한계를 넘고 노드·가용 영역 장애에도 데이터 서비스를 유지하기 위해 분산 배치·복제·조정 구조가 필요함

### 쉽게 이해하기 (학습용)
- 하나의 큰 장부를 여러 지점에 나누고 사본과 합의 규칙으로 하나처럼 쓰는 데이터베이스임

## Ⅱ. 특징

- 파티션 매핑과 재분산으로 노드 추가 시 저장 용량과 키 범위 처리량을 확장함
- 복제본을 장애 영역에 분산하고 정족수·리더 전환으로 일부 노드 장애 중 요청을 처리함
- 데이터 위치·분할·복제 투명성으로 응용이 물리 노드 주소 대신 논리 키·질의를 사용함
- 네트워크 단절·복제 지연·교차 파티션 트랜잭션·시계 순서·재분산 비용을 함께 관리해야 함

### 쉽게 이해하기 (학습용)
- 수평 확장과 부분 장애 대응은 좋아지지만 네트워크·사본·분산 거래 비용이 추가됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 DB | 분산 DB |
|:---|:---|:---|
| 데이터 배치 | 한 DB 인스턴스의 저장 구조 중심 | 키·범위별 파티션과 장애 영역별 복제본 |
| 확장 방식 | 인스턴스·스토리지 증설과 읽기 복제 | 노드 추가·파티션 재분산으로 수평 확장 |
| 트랜잭션·일관성 | 단일 로그·락·격리 수준으로 통제 | 복제 합의·분산 커밋·복제 지연·충돌을 통제 |

> 요약: 단일 DB는 한 실행·저장 경로를 관리하고, 분산 DB는 파티션 라우팅·복제 합의·재분산과 교차 노드 트랜잭션을 관리함.

### 쉽게 이해하기 (학습용)
- 단일 DB는 한 지점, 분산 DB는 여러 지점의 배치·확장·거래 규칙을 관리함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 파티션 맵·라우터 | 키·범위를 담당 노드에 연결하고 질의를 대상 파티션으로 전달함 |
| 분산 실행기 | 여러 파티션의 연산을 계획하고 중간 결과를 병합함 |
| 복제 로그·합의 | 복제본 변경 순서와 리더·커밋 지점을 일치시킴 |
| 분산 트랜잭션 | 여러 파티션의 준비·커밋·중단을 하나의 결과로 조정함 |
| 장애 감지·복구 | 실패 노드를 판정하고 복제본 보충·파티션 재분산을 수행함 |

```text
클라이언트 -> 파티션 라우터 -> 파티션 A/B/C
                              \-> 복제본·합의
```

> 요약: 파티션 라우터와 분산 실행기가 대상 노드를 선택하고 복제 합의·분산 트랜잭션이 변경 결과를 조정함.

### 쉽게 이해하기 (학습용)
- 지점 안내표, 여러 지점 실행기, 사본 합의와 분산 거래 조정기로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
요청 수신 -> 파티션 선택 -> 복제본 읽기·쓰기 -> 일관성·커밋 판정 -> 결과 병합
```

1. **요청 수신**: 라우터가 키·질의·일관성·트랜잭션 정보를 수신함
2. **파티션 선택**: 파티션 맵에서 대상 노드와 복제본 집합을 결정함
3. **복제본 처리**: 대상 복제본이 읽기 또는 로그 기반 쓰기를 수행함
4. **일관성·커밋 판정**: 정족수나 분산 커밋 조건을 충족했는지 확인함
5. **결과 병합**: 분산 실행기가 파티션별 결과를 정렬·집계해 반환함

> 요약: 분산 DB는 파티션별 복제본에서 요청을 처리하고 정족수·분산 커밋 조건을 확인한 뒤 결과를 병합함.

### 쉽게 이해하기 (학습용)
- 키로 담당 지점을 찾고 사본 확인과 여러 지점 커밋을 거쳐 결과를 합침

## Ⅵ. 실무 사례

1. 멀티테넌트 DB는 테넌트 키로 파티셔닝하고 최대 파티션 요청 점유율·재분산 시간을 확인함
2. 주문 DB는 주문 집계 단위로 데이터를 배치하고 교차 파티션 트랜잭션 비율·p99 커밋 지연을 확인함

### 쉽게 이해하기 (학습용)
- 테넌트별 분산에 적용하고 교차 샤드 거래·재분산 시간·복제 지연을 감시함

## Ⅶ. 결론

- 분산 데이터베이스는 파티션 키·복제·일관성·트랜잭션 경계와 장애 복구 비용을 기준으로 적용해야 함
- 단일 노드 한계를 수치로 확인한 뒤 도입하고 교차 파티션 비율·복제 지연·복구 시간을 SLO로 관리해야 함

### 쉽게 이해하기 (학습용)
- 지점을 늘리기 전에 한 지점의 한계를 확인하고 지점 간 거래와 복구 시간을 계속 재야 함
