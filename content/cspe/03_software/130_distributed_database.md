## 미리 알고가기

- 분산 DB는 데이터를 여러 노드에 나누어 저장하면서 하나의 데이터베이스처럼 보이게 하는 구조임
- 샤딩은 데이터를 나누는 방식이고 복제는 같은 데이터를 여러 노드에 두는 방식임
- 2단계 커밋과 합의 프로토콜은 여러 노드에 걸친 정합성을 맞추는 대표 기법임

## Ⅰ. 개요

- **정의/개념**: 분산 데이터베이스는 데이터를 여러 서버나 지역에 나누어 저장하고도 사용자에게는 하나의 논리 DB처럼 보이게 하며, 분산 저장과 복제와 분산 질의를 함께 관리하는 데이터베이스 구조임
- **배경/필요성**: 데이터 양과 사용자 수가 커지고 지역별 가용성과 장애 대응 요구가 높아지면서 단일 서버 DB만으로는 확장성과 복원력이 부족해 분산 DB가 필요해짐

## Ⅱ. 특징

- 노드 추가로 저장 용량과 처리량을 수평 확장하기 쉬움
- 장애가 나도 일부 복제본과 다른 노드로 서비스를 이어갈 수 있음
- 위치별 분산 배치로 지연 시간을 줄이거나 지역 가용성을 높일 수 있음
- 정합성과 트랜잭션과 운영 복잡도가 단일 DB보다 크게 높아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 DB | 분산 DB |
|:---|:---|:---|
| 확장 방식 | 수직 확장 중심 | 수평 확장 중심 |
| 장애 영향 | 단일 장애점이 큼 | 일부 노드 장애를 흡수하기 쉬움 |
| 정합성 관리 | 비교적 단순함 | 분산 트랜잭션과 복제 지연을 다뤄야 함 |
| 운영 난도 | 구조가 단순함 | 설계와 관측과 복구가 복잡함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Partitioning | 데이터를 키 기준으로 여러 노드에 분산함 |
| Replication | 같은 데이터를 여러 노드에 복제해 가용성을 높임 |
| Query Router | 요청을 적절한 노드로 보내고 결과를 합침 |
| Transaction / Consensus | 여러 노드에 걸친 정합성과 순서를 맞춤 |
| Monitoring / Recovery | 지연과 장애와 재동기화를 운영함 |

```text
클라이언트 -> 라우터 -> 샤드 A/B/C
                    \-> 복제본
```

## Ⅴ. 원리 및 절차 흐름도

```text
분할 키 결정 -> 데이터 분산 저장 -> 복제 유지 -> 분산 질의 -> 장애 복구/재동기화
```

1. **분할 키 결정**: 접근 패턴에 맞는 샤드 키를 정함
2. **분산 저장**: 데이터를 여러 노드에 나누어 적재함
3. **복제 유지**: 장애 대비용 복제본을 운영함
4. **분산 질의**: 라우터가 대상 노드에 질의를 전달하고 결과를 합침
5. **복구와 재동기화**: 장애 후 누락 데이터를 다시 맞춤

## Ⅵ. 실무 적용 및 유의점

1. 글로벌 서비스와 대용량 거래 시스템은 분산 DB가 필요할 수 있지만 샤드 키가 한쪽으로 몰리면 특정 노드만 과열되므로 샤드별 요청 비율과 데이터 편차와 재분산 시간을 기준으로 확인함
2. 여러 노드에 걸친 트랜잭션은 정합성을 높여도 지연이 커질 수 있으므로 분산 트랜잭션 범위를 최소화하고 교차 샤드 트랜잭션 비율과 평균 응답 시간과 복제 지연으로 확인함

## Ⅶ. 결론

- 분산 데이터베이스는 확장성과 가용성을 얻는 대신 정합성과 운영 복잡도를 함께 떠안는 구조이므로 샤드 키와 트랜잭션 경계를 먼저 설계해야 함
