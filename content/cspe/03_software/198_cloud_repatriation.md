## 미리 알고가기

- 클라우드 회귀는 퍼블릭 클라우드 워크로드·데이터를 사설 클라우드·온프레미스·코로케이션으로 이전함
- 회귀는 전면 철수가 아니라 비용·지연·규제·통제 기준으로 워크로드 배치를 다시 정하는 결정임
- TCO는 클라우드 사용·데이터 반출과 목표 환경의 장비·라이선스·인력·시설·전환 비용을 포함함
- 데이터 중력은 데이터 규모가 커질수록 연산과 연계 시스템을 데이터 가까이에 두려는 제약임
- 관리형 서비스 의존성은 목표 환경에서 대체·재구현해야 하는 API·데이터 모델·운영 기능임
- 출구 계획은 데이터 내보내기·호환 형식·전환·검증·기존 자원 폐기·롤백 조건을 포함함

## 작성 근거(검토용)

- 클라우드 회귀는 워크로드 경제성, 데이터 중력, 관리형 의존성, 운영 역량, 이전·롤백을 핵심 축으로 설명함
- 비교표는 클라우드 유지·최적화와 회귀의 비용·기술·운영·위험 조건을 같은 수준에서 대비함
- 절차는 후보 평가·의존성 전환·데이터 동기화·트래픽 전환·검증·기존 자원 폐기 순서를 따름

## Ⅰ. 개요

- **정의/개념**: 클라우드 회귀는 퍼블릭 클라우드의 특정 워크로드와 데이터를 비용·지연·규제·통제 기준에 따라 사설 또는 자체 운영 환경으로 이전하는 배치 전략임
- **배경/필요성**: 지속 부하 비용·데이터 반출·관리형 서비스 종속·규제 통제가 운영 제약이 되면 목표 환경을 다시 판단할 기준이 필요함

## Ⅱ. 특징

- 전체 클라우드가 아니라 워크로드별 부하·데이터·의존성·운영 요구를 평가함
- 현재 약정·할인 반영 비용과 목표 환경의 장비·인력·시설·전환 비용을 같은 기간 TCO로 비교함
- 관리형 서비스 API·데이터 형식·IAM·관측 기능의 대체 범위가 이전 난이도를 결정함
- 데이터 동기화·점진 전환·롤백·기존 사본 폐기로 서비스 연속성과 데이터 정합성을 검증함

## Ⅲ. 종류 및 비교

| 판단 기준 | 클라우드 유지·최적화 | 클라우드 회귀 |
|:---|:---|:---|
| 부하 조건 | 수요가 변동해 탄력 확장을 사용 | 부하가 지속돼 자체 용량 계획이 가능 |
| 비용 구조 | 사용량·약정·관리형 서비스 비용 | 장비·시설·라이선스·인력·운영 비용 |
| 데이터 조건 | 클라우드 내 저장·처리와 연계가 중심 | 데이터 반출·지역 처리·로컬 연계가 중심 |
| 서비스 의존 | 관리형 API·운영 기능을 계속 활용 | 대체 제품·오픈 인터페이스·자체 운영으로 전환 |
| 운영 책임 | 공급자와 공유 책임으로 기반 운영 | 조직이 용량·패치·백업·복구를 직접 담당 |
| 주요 위험 | 예측 밖 사용 비용·서비스 종속·반출 비용 | 전환 실패·용량 부족·운영 인력·초기 투자 |

> 요약: 회귀는 목표 TCO와 데이터 처리 위치·통제 요구가 전환·운영 위험을 정당화할 때 워크로드별로 결정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 워크로드 평가 | 사용량·SLO·데이터 흐름·규제·서비스 의존성을 분석함 |
| TCO·위험 모델 | 현재·목표 환경의 비용과 전환·운영 위험을 같은 기간으로 비교함 |
| 목표 플랫폼 | 서버·스토리지·네트워크·가상화·오케스트레이션 용량을 설계함 |
| 이식 계층 | 이미지·IaC·오픈 데이터 형식·대체 API로 종속 기능을 전환함 |
| 데이터 이전 | 초기 복제·변경분 동기화·무결성 검증·보존 정책을 수행함 |
| 전환·운영 체계 | 트래픽 절체·롤백·관측·백업·기존 클라우드 자원 폐기를 관리함 |

```text
워크로드 평가 -> TCO·위험 판정 -> 목표 플랫폼·이식 -> 데이터 동기화
                                                       |
기존 클라우드 폐기 <- 운영 검증 <- 트래픽 전환·롤백 -+
```

> 요약: 회귀는 경제성 판정 후 기술 종속과 데이터를 이전하고 서비스 검증 뒤 기존 자원을 폐기함.

## Ⅴ. 원리 및 절차 흐름도

```text
후보 선정 -> 의존성·TCO 검증 -> 목표 환경 구축 -> 데이터 동기화 -> 점진 전환 -> 검증·폐기
```

1. **후보 선정**: 사용량·비용·SLO·규제 조건으로 회귀 후보를 판정함
2. **타당성 검증**: 관리형 의존성·이전 비용·목표 TCO·운영 인력을 함께 평가함
3. **목표 환경 구축**: 용량·보안·관측·백업·복구 기준을 충족하도록 플랫폼을 구성함
4. **데이터 동기화**: 초기 복제 후 변경분을 반영하고 건수·체크섬·RPO를 확인함
5. **점진 전환**: 일부 트래픽을 목표 환경으로 보내 SLO와 롤백 조건을 검증함
6. **완료·폐기**: 전체 절체 후 잔존 데이터와 종속 자원을 확인하고 기존 환경을 종료함

> 요약: 회귀 타당성을 검증한 뒤 데이터와 트래픽을 단계적으로 옮기고 SLO 확인 후 기존 자원을 폐기함.

## Ⅵ. 실무 사례

1. 상시 ML 추론 서비스는 사설 GPU 클러스터로 이전하고 요청당 비용·p99 추론 지연을 확인함
2. 분석 저장소는 개방형 포맷으로 동기화해 로컬 플랫폼으로 옮기고 체크섬 불일치·전환 RPO를 확인함

## Ⅶ. 결론

- 클라우드 회귀는 TCO·데이터 중력·서비스 종속·운영 역량을 검증하고 워크로드별로 결정함
