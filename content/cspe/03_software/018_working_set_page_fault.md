## Ⅰ. 개요
- **정의**: 일정 시간 동안 프로세스가 참조하는 페이지 집합(워킹셋)과 해당 페이지 부재 시 발생하는 인터럽트(페이지 폴트)
- **배경/필요성**: 메모리 할당량을 워킹셋 크기에 맞추어 스래싱을 방지할 필요가 있음(016 참조)
- **비유**: 요리사가 자주 쓰는 식재료(워킹셋)를 조리대에 두고, 없는 재료는 창고에서 가져오는(페이지 폴트) 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 관리 최적화 원리 | 워킹셋 윈도우(Δ)와 스래싱 관계 | 워킹셋 크기와 프레임 할당량의 관계를 명시해야 함 |

> 요약: 워킹셋 기반 프레임 할당으로 페이지 폴트를 최소화하고 스래싱을 방지하는 기법임

## Ⅱ. 구성요소
```text
Time Window (delta)
|<--------->|
Page refs: ... 3 5 2 3 7 5 2 ...
Working Set = {2, 3, 5, 7}
                |
                v
Frame Allocation >= |Working Set|
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 워킹셋 윈도우(Δ) | 최근 Δ시간 내 참조된 페이지를 추적하는 시간 구간 | 최근 주문 기록 조회 기간 |
| 워킹셋 크기(WSS) | 윈도우 내 고유 페이지 수로 필요 프레임 수를 결정함 | 조리대에 올릴 재료 가짓수 |
| 페이지 폴트 | 참조 페이지가 메모리에 없을 때 발생하는 트랩 | 재료가 조리대에 없어 창고로 가는 상황 |
| 페이지 교체 알고리즘 | 폴트 시 희생 페이지를 선택하는 정책(LRU, Clock 등) | 조리대 공간 확보를 위해 안 쓰는 재료를 치우는 규칙 |

> 요약: 윈도우·WSS·폴트·교체 알고리즘이 메모리 할당 최적화의 핵심 요소임

## Ⅲ. 절차
```text
페이지 참조 --> 메모리 존재 확인 --> 폴트 처리 --> WSS 갱신
```
- 1단계: CPU가 가상 주소를 통해 페이지를 참조함
- 2단계: 해당 페이지가 물리 메모리에 존재하는지 확인함(TLB→페이지 테이블)
- 3단계: 부재 시 페이지 폴트가 발생하고 디스크에서 페이지를 적재함
- 4단계: 워킹셋 윈도우를 갱신하여 할당 프레임 수를 조정함

> 요약: 참조 → 존재 확인 → 폴트 처리 → WSS 갱신 순서로 동작함

## Ⅳ. 문제점
- 윈도우 크기 설정 곤란: Δ가 너무 작으면 폴트 빈발, 너무 크면 메모리 낭비가 발생함
- 실시간 추적 비용: 모든 페이지 참조를 기록하면 오버헤드가 과다함
- 급격한 지역성 변화: 프로그램 단계 전환 시 WSS가 급변하여 폴트가 집중됨

> 요약: 윈도우 설정, 추적 비용, 지역성 급변이 워킹셋 관리의 한계임

## Ⅴ. 개선방안
1. 단기: 페이지 폴트 빈도(PFF) 기반 동적 Δ 조정으로 윈도우 크기를 자동 튜닝함
2. 중기: 참조 비트 샘플링(Clock 알고리즘 변형)으로 추적 오버헤드를 감소시킴
3. 장기: 프리페칭(prefetching)으로 단계 전환 시 예상 페이지를 선제 적재함

> 요약: PFF 기반 조정 → 샘플링 → 프리페칭 순으로 개선함

## Ⅵ. 전망
- 발전 방향: 머신러닝 기반 페이지 접근 패턴 예측으로 선제적 메모리 관리가 연구 중임
- 기술사적 판단: 가상 메모리 성능 최적화의 핵심 개념으로 OS 설계에서 중요도가 지속됨
- 기술사 제언: 대규모 메모리 시스템에서 워킹셋 추정 정확도와 오버헤드 간 균형을 검토할 필요가 있음
