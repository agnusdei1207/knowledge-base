## 미리 알고가기

- working set은 일정 시간 창에서 실제로 참조되는 페이지 집합임
- page fault는 필요한 페이지가 메모리에 없을 때 발생하는 예외임
- 워킹 셋보다 할당 프레임이 적으면 반복 참조 페이지가 퇴출되어 페이지 폴트가 증가함

## 작성 근거(검토용)

- 워킹 셋은 필요한 메모리 규모, 페이지 폴트는 프레임 부족·참조 변화의 결과 신호로 구분함
- 시간 창·상주 집합·폴트 감시·회수 정책을 추정과 재배분 흐름으로 연결함
- 데이터베이스와 다중 작업 호스트를 분리해 추정 오차와 swap I/O를 검증함

## Ⅰ. 개요

- **정의/개념**: 워킹 셋은 일정 시간 구간에 프로세스가 참조한 페이지 집합이고, 페이지 폴트는 참조한 페이지가 물리 메모리에 없을 때 발생하는 예외임
- **배경/필요성**: 프로세스의 페이지 참조 범위가 시간에 따라 달라지므로 워킹 셋과 페이지 폴트율을 기준으로 프레임을 배분해야 함

## Ⅱ. 특징

- 워킹 셋은 시간 구간 내 페이지 참조 지역성을 수치화함
- 페이지 폴트율 증가는 상주 집합이 현재 참조 범위를 수용하지 못한다는 신호가 됨
- 페이지 폴트가 반복되면 프로세스 실행시간 중 페이지 적재 I/O 대기 비중이 증가함
- 워킹 셋 변화는 프로세스 단계 전환과 작업 특성 변화를 반영함

## Ⅲ. 종류 및 비교

| 판단 기준 | 워킹 셋 관점 | 페이지 폴트 관점 |
|:---|:---|:---|
| 초점 | 필요한 메모리 규모 예측 | 발생한 fault 수 관찰 |
| 활용 방식 | 참조 시간 창으로 필요 프레임 수 추정 | 발생한 page fault 횟수·비율 측정 |
| 한계 | 시간 창 설정에 따라 추정값이 달라짐 | 원인 분석 없이 결과만 보게 됨 |
| 제어 대상 | 상주 집합 크기 | 메모리 압박 경보·회수 시점 |

> 요약: 워킹 셋은 필요한 프레임 규모를 추정하고, 페이지 폴트는 현재 상주 집합이 참조를 수용하는지 보여줌.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 참조 시간 창 | 최근 참조를 포함할 기간을 정해 워킹 셋을 추정함 |
| 상주 집합 | 프로세스에 현재 할당한 물리 프레임을 나타냄 |
| 페이지 폴트 감시기 | 주요·경미 폴트 빈도로 메모리 압박을 확인함 |
| 회수 정책 | 워킹 셋을 초과한 페이지를 회수하거나 프레임을 재배분함 |

> 요약: 참조 시간 창으로 워킹 셋을 추정하고 상주 집합·폴트 추세에 따라 프레임을 재배분함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 참조 이력 수집  | --> | working set 추정 | --> | 프레임 배분 조정 | --> | fault 감시      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **참조 이력 수집**: 최근 페이지 참조를 시간 창 기준으로 기록함
2. **working set 추정**: 현재 필요한 페이지 집합과 크기를 계산함
3. **프레임 배분 조정**: 부족한 프로세스에는 프레임을 늘리고 과다 점유는 회수함
4. **fault 감시**: page fault 추세로 메모리 압박과 스래싱 징후를 확인함

## Ⅵ. 실무 사례

1. 데이터베이스 서버는 참조 시간 창으로 상주 집합을 조정하고 워킹 셋 추정 오차와 주요 폴트율을 확인함
2. 다중 작업 호스트는 총 워킹 셋으로 실행 작업 수를 제한하고 swap I/O와 페이지 회수율을 확인함

## Ⅶ. 결론

- 메모리 배분은 워킹 셋으로 필요한 프레임을 추정하고 페이지 폴트 추세로 부족 여부를 검증함
