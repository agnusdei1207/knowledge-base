## Ⅰ. 개요
- **정의**: 일정 시간 창(window) 내에 프로세스가 참조하는 페이지 집합
- **배경/필요성**: 프로세스에 할당할 적정 프레임 수를 결정하지 않으면 스래싱이 발생함 (016 참조)
- **비유**: 요리사가 지금 조리 중인 레시피에 필요한 재료만 조리대에 올려두는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스래싱 방지 원리 파악 | 워킹셋 크기와 프레임 할당의 관계 | 워킹셋 윈도우(delta)의 의미를 정확히 기술할 것 |

> 요약: 시간 창 기반 참조 페이지 집합을 파악하여 적정 프레임을 할당하는 모델임

## Ⅱ. 구성요소
```text
Time Window (delta)
|<--------->|
Page refs:  A B A C B A D
                        |
                        v
Working Set = {A, B, C, D} at time t
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 윈도우(delta) | 최근 참조를 추적하는 시간 구간의 크기 | 조리대 위에 재료를 유지하는 시간 |
| 워킹셋 W(t,delta) | 시각 t에서 delta 내 참조된 고유 페이지 집합 | 현재 조리대 위에 올라와 있는 재료 목록 |
| 페이지 폴트율 | 단위 시간당 물리 메모리에 없는 페이지 참조 횟수 | 조리대에 없어서 냉장고까지 다녀온 횟수 |

> 요약: 윈도우·워킹셋·페이지 폴트율 세 요소로 메모리 할당 적정성을 판단함

## Ⅲ. 절차
```text
참조 기록 수집 --> 워킹셋 산출 --> 프레임 할당 조정 --> 스래싱 판별
```
- 1단계: 프로세스의 페이지 참조 이력을 시간 순으로 기록함
- 2단계: 윈도우 delta 내 고유 페이지 수를 계산하여 워킹셋 크기를 산출함
- 3단계: 워킹셋 크기 이상의 물리 프레임을 프로세스에 할당함
- 4단계: 전체 워킹셋 합이 가용 프레임을 초과하면 스래싱으로 판별하고 다중도를 조절함

> 요약: 참조 기록에서 워킹셋을 산출하고 프레임 부족 시 다중도를 낮추어 스래싱을 방지함

## Ⅳ. 문제점
- 윈도우 설정 난이도: delta가 너무 작으면 워킹셋을 과소 추정하고, 너무 크면 불필요 페이지를 포함함
- 추적 오버헤드: 매 참조마다 타임스탬프를 기록하면 OS 부담이 증가함
- 동적 변화 지연: 프로세스의 지역성 전이(phase change) 시 워킹셋 갱신이 뒤처짐

> 요약: 윈도우 설정, 추적 비용, 지역성 전이 지연이 워킹셋 모델의 한계임

## Ⅴ. 개선방안
1. 단기: PFF(Page Fault Frequency) 기법으로 폴트율 상·하한 기준을 두어 윈도우 설정 부담을 줄임
2. 중기: 참조 비트 주기적 초기화 방식으로 근사 워킹셋을 저비용으로 추적함
3. 장기: 머신러닝 기반 지역성 예측으로 위상 전이를 선제 감지하여 프레임을 사전 조정함

> 요약: PFF, 참조 비트 근사, 지역성 예측으로 워킹셋 모델의 실용성을 높임

## Ⅵ. 전망
- 발전 방향: 컨테이너·서버리스 환경에서 워크로드별 메모리 자동 스케일링에 워킹셋 개념이 재활용됨
- 기술사적 판단: 메모리 과할당 방지와 비용 최적화의 핵심 지표로 클라우드에서 중요성이 증가함
- 기술사 제언: 워킹셋 기반 자동 스케일링 정책을 SLA와 연계하여 설계할 필요
