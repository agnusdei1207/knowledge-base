# 📖 【암기용】 개념 완전 이해

## 한눈에
- **지역성 (Locality)**: 프로세스가 특정 시간 동안 메모리의 특정 영역을 집중적으로 참조하는 성질.
- **워킹 셋 (Working Set)**: 지역성에 기반하여, 프로세스가 원활하게 실행되기 위해 **특정 시점에 유지해야 하는 페이지들의 집합**.
- **페이지 폴트 빈도 (PFF, Page Fault Frequency)**: 페이지 폴트가 발생하는 비율을 모니터링하여, 프로세스에게 줄 **프레임 수를 동적으로 조절**하는 기법.
- **핵심 직관**: 시험 공부(프로세스)를 할 때, 지금 당장 필요한 참고서 3권(Working Set)이 책상 위에 없으면 계속 책꽂이로 달려가야 함(Page Fault). PFF는 학생이 너무 자주 책꽂이로 가면 책상을 넓혀주고, 한참 안 가면 책상을 뺏어오는 관리자 역할.

## 깊이 이해
- **Denning의 Working Set 이론**: 프로세스의 실행은 '안정 상태(Working Set 유지)'와 '전이 상태(새로운 Working Set으로 교체)'를 반복함.
- **델타($\Delta$) - 윈도우 크기**: 얼마나 과거까지를 워킹 셋으로 인정할 것인가 하는 시간 간격. 델타가 너무 작으면 필요한 페이지가 누락되고, 너무 크면 메모리가 낭비됨.
- **PFF의 임계값 제어**:
    - **Upper Bound**: 이 선을 넘으면 "이놈은 프레임이 부족해서 허덕이고 있구나"라고 판단해 프레임을 추가 할당.
    - **Lower Bound**: 이 선 밑으로 내려가면 "이놈은 프레임이 남는구나"라고 판단해 프레임을 회수.
- **가치**: 스레싱(Thrashing)을 방지하고 시스템 전체의 처리량을 극대화하는 구체적인 실현 방법.

## 연결 개념
- **Thrashing (015)**: 워킹 셋과 PFF가 막으려는 재앙.
- **Locality (018)**: 워킹 셋 모델의 과학적 근거.
- **Page Replacement (017)**: 프레임이 찼을 때 어떤 놈을 뺄 것인가의 문제 (018은 몇 개를 줄 것인가의 문제).

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 프로세스의 **지역성(Locality)**을 정량화하여 실행에 필요한 최적의 메모리 자원을 동적으로 할당함으로써 **스레싱(Thrashing)**을 방지하는 기법임.
> 2. **기술적 핵심**: **Working Set**은 참조 이력 기반의 사전적 자원 할당을, **PFF**는 페이지 부재율 기반의 사후적 피드백 제어를 통해 메모리 효율을 극대화함.
> 3. **가치**: 다중 프로그래밍 정도(MPD)를 시스템이 수용 가능한 한계치 내에서 조절하여 전체 응답성과 처리량의 균형을 유지함.

## Ⅰ. 스레싱 방지의 핵심 기제, Working Set과 PFF 개요
- **Working Set**: 프로세스가 특정 시간 간격($\Delta$) 동안 참조한 페이지들의 집합으로, 지역성에 기반한 최소 필요 메모리 모델.
- **PFF (Page Fault Frequency)**: 페이지 부재 발생 빈도를 측정하여 상한/하한 임계치에 따라 프레임 할당량을 동적으로 조절하는 기법.

## Ⅱ. Working Set Model 상세 분석

### 1. 주요 개념 및 파라미터
- **Working Set Window ($\Delta$)**: 워킹 셋을 결정하는 과거 시간의 범위.
- **Working Set Size ($WSS_i$)**: 시점 $t$에서의 워킹 셋에 포함된 고유 페이지 수.
- **제어 정책**: $\sum WSS_i > \text{Total Frames}$ 이면, 프로세스 중 하나를 Suspend(Swap-out) 시켜 스레싱 예방.

### 2. 지역성(Locality)의 종류
| 구분 | 시간 지역성 (Temporal) | 공간 지역성 (Spatial) |
|:---:|:---|:---|
| **정의** | 최근 참조된 주소가 곧 다시 참조됨 | 참조된 주소 인근 주소가 참조됨 |
| **예시** | Loop, Stack, Counting 변수 | Array, 순차적 코드 실행 |
| **활용** | LRU 교체 알고리즘의 근거 | Prefetching, 워킹 셋 구성 |

## Ⅲ. PFF (Page Fault Frequency) 동작 메커니즘

### 1. 프레임 할당 조절 루프 (ASCII Diagram)
```text
  Page Fault Rate
       ^
       |   (A) 할당 증가 [Upper Bound 초과]
       |  ------------------------- (Upper Threshold)
       |   (B) 상태 유지
       |  ------------------------- (Lower Threshold)
       |   (C) 프레임 회수 [Lower Bound 미만]
       +----------------------------> Time
```

### 2. 동작 특징
- 페이지 폴트가 발생할 때만 프레임 할당량을 조정하므로 오버헤드가 상대적으로 적음.
- 프로세스의 변화하는 메모리 요구량에 즉각적으로 반응하는 피드백 제어 시스템.

## Ⅳ. Working Set vs PFF 비교

| 비교 항목 | Working Set Model | PFF (Page Fault Frequency) |
|:---:|:---|:---|
| **제어 방식** | 사전적/추정적 (History 기반) | 사후적/반응적 (Fault Rate 기반) |
| **판단 근거** | 참조된 페이지의 종류와 시간 | 페이지 부재 발생 시간 간격 |
| **장점** | 스레싱을 보다 확실히 예방 | 오버헤드가 적고 구현이 단순함 |
| **오버헤드** | 지속적인 참조 기록 모니터링 필요 | 페이지 폴트 시에만 계산 수행 |

## Ⅴ. 기술적 심화: 부하 제어(Load Control)와의 연계
- **MPD 조정**: Working Set 총합이 물리 메모리를 넘어서면 중기 스레줄러가 프로세스를 통째로 Swap-out 시켜 시스템 부하를 낮춤.
- **Global Replacement**: PFF는 전체 시스템의 프레임 풀에서 유연하게 할당량을 조정하는 Global 정책과 결합될 때 효과가 큼.

## Ⅵ. 기술사 관점의 결론 및 제언
- Working Set과 PFF는 **'한정된 자원의 효율적 분배'**라는 운영체제의 본질적 가치를 실현하는 도구임.
- **실무 제언**: 가상화 환경(VM, Docker)에서 **Memory Ballooning** 기술이나 **KSM(Kernel Same-page Merging)** 등은 현대적인 워킹 셋 관리의 연장선상에 있으며, 이를 통해 집적도를 높이되 개별 워크로드의 스레싱 리스크를 관리하는 지혜가 필요함.
