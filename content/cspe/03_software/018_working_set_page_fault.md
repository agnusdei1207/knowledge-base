# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 워킹셋·페이지 폴트 빈도(PFF)는 **각 프로세스에 "실제로 필요한 페이지 집합"만큼 물리 프레임을 보장해 페이지 폴트를 적정 수준으로 유지하는 프레임 할당 전략**으로, 지역성을 근거로 스레싱을 예방한다.
- **왜 필요한가**: 프레임을 너무 적게 주면 폴트가 폭증해 스레싱(015 참조)에 빠지고, 너무 많이 주면 다른 프로세스가 굶는다. 프로세스마다 "지금 필요한 만큼"을 동적으로 맞추는 기준이 있어야 한다.
- **핵심 직관**: 공부에 지금 실제로 펼쳐야 할 책 몇 권(워킹셋)만 책상에 보장하면 술술 진행되고, 그보다 적으면 계속 책을 꺼냈다 넣었다(폴트) 하며 진도가 안 나간다. 꺼내는 빈도(PFF)를 보고 책상 크기를 조절한다.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 답안용에 나오는 표기를 비유와 함께 먼저 세운다. 가상 메모리·페이지 폴트의 기본은 016, 스레싱은 015 참조.

| 용어/표기 | 의미 | 비유·예 |
| --- | --- | --- |
| 워킹셋 (상위 키워드) | 최근 Δ 시간 동안 참조한 서로 다른 페이지의 집합 | 지금 공부에 실제 펼치는 책 몇 권 |
| 워킹셋 윈도우 (Δ) | 워킹셋을 판단하는 최근 참조 시간 범위 | "최근 10분간" 기준 |
| 워킹셋 크기 WSS(Δ) | 그 윈도우 안 서로 다른 페이지 수 | 그동안 펼친 책 권수 |
| 페이지 폴트 (Page Fault) | 참조 페이지가 메모리에 없어 디스크에서 가져옴 | 필요한 책이 없어 서가에서 꺼냄 |
| PFF (Page Fault Frequency) | 페이지 폴트 발생률로 프레임 수를 조절하는 기법 | 책 꺼내는 빈도로 책상 크기 조정 |
| PFF 상·하한 | 폴트율 임계값, 초과 시 프레임↑·미만 시 프레임↓ | 너무 자주/드물면 책상 조정 |
| 지역성 (Locality) | 최근·인접 참조를 다시 참조하는 경향 | 방금 본 책 근처를 또 봄 |
| 시간 지역성 | 최근 참조한 것을 곧 다시 참조 | 방금 편 쪽을 또 봄 |
| 공간 지역성 | 참조한 것 근처를 참조 | 옆 쪽·다음 쪽을 봄 |
| 스레싱 (Thrashing) | 폴트 처리에 CPU를 다 써 처리량 급락(015) | 책 꺼내기만 반복해 공부 못 함 |

## 깊이 이해
- **배경·문제의식**: 전역 프레임 관리에서는 한 프로세스가 프레임을 독식하면 다른 프로세스가 굶어 폴트가 폭증한다. 스레싱(015 참조)을 예방하려면 "각 프로세스에 얼마의 프레임을 줄 것인가"를 정해야 하는데, 이 답이 워킹셋이다. 프로그램은 지역성 때문에 한 시점에 소수 페이지만 집중 참조하므로, 그 집합만 보장하면 폴트가 급감한다.
- **작동 원리(어떻게+왜)**: 워킹셋 모델은 최근 Δ 동안 참조된 페이지 집합 WS(t,Δ)를 프로세스별로 추적하고, 그 크기만큼 프레임을 보장한다. 모든 프로세스의 워킹셋 합이 물리 프레임을 넘으면 한 프로세스를 suspend해 다중 프로그래밍 정도를 낮춘다. PFF는 워킹셋을 직접 추적하는 대신 결과 지표인 폴트율만 감시한다 — 폴트율이 상한을 넘으면 프레임을 더 주고, 하한 밑이면 회수한다. 둘 다 "필요한 만큼"을 지역성으로 근사하지만, 워킹셋은 집합을 직접 추적하고 PFF는 폴트율로 피드백 제어한다.
- **비유**: 워킹셋은 "지금 펼쳐 놓고 보는 책 목록을 직접 세어" 그만큼 책상을 확보하는 방식이고, PFF는 "책을 얼마나 자주 서가에서 꺼내는지"만 보고 너무 잦으면 책상을 넓히고 뜸하면 좁히는 방식이다.
- **구체 예시**: Δ=10,000 참조에서 프로세스가 페이지 {1,2,5,6,7}만 반복 참조하면 WSS=5이므로 프레임 5개를 보장하면 폴트가 거의 없다. PFF 상한 0.01·하한 0.002로 두고, 폴트율이 0.015로 상한을 넘으면 프레임을 늘리고, 0.001로 하한 밑이면 프레임을 회수해 다른 프로세스에 돌린다.
- **흔한 오해·주의점**: (1) **워킹셋 크기는 고정이 아니다** — 실행 국면(phase) 전환 시 급변하며, Δ가 너무 작으면 워킹셋을 과소평가해 폴트가 늘고 너무 크면 프레임을 낭비한다. (2) **PFF는 국면 전환 순간 일시적 폴트 급증을 스레싱으로 오판할 수 있다** — 짧은 스파이크와 지속 상승을 구분해야 한다. (3) 지역성이 약한(랜덤 접근) 워크로드는 워킹셋이 커서 두 기법 모두 효과가 제한된다.

## 연결 개념
- 프로세스 스레싱(015 참조) — 워킹셋·PFF가 예방하려는 성능 붕괴 현상
- 가상 메모리·요구 페이징(016 참조) — 페이지 폴트가 발생하는 전제 구조
- 페이지 교체 알고리즘(017 참조) — 지역 교체 시 워킹셋 밖 페이지를 victim으로 선택

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 워킹셋은 최근 Δ 동안 참조한 페이지 집합으로 프로세스의 "필요 프레임"을 정의하고, PFF는 폴트율 피드백으로 같은 목표를 근사함.
> 2. **가치**: 지역성을 근거로 프레임을 적정 배분해 스레싱을 예방하고 다중 프로그래밍 정도를 안전하게 유지함.
> 3. **판단 포인트**: 국면이 안정적이면 워킹셋 직접 추적, 오버헤드를 줄이려면 PFF 피드백이 적합함.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
| --- | --- | --- |
| 워킹셋 모델 정의 | Δ 윈도우·WSS·프레임 보장 | 워킹셋 크기를 고정값으로 단정 |
| PFF 제어 원리 | 폴트율 상·하한 피드백 조절 | 상·하한 양방향 조절 누락 |
| 스레싱 예방 연계 | 워킹셋 합 > 프레임 시 suspend | 스레싱 원인·메커니즘 혼동 |

> 요약: 워킹셋을 Δ 기반 필요 프레임으로 정의하고, PFF의 폴트율 피드백과 함께 스레싱 예방 메커니즘을 제시함.

## Ⅰ. 개요 및 필요성
- 개요: 최근 Δ 참조 페이지 집합만큼 프레임을 보장해 폴트를 적정화하는 할당 전략임
- 배경: 전역 프레임 관리는 특정 프로세스 독식·기아로 폴트가 폭증해 스레싱을 유발함
- 필요성: 프로세스별 "필요한 만큼"을 지역성으로 정의해 스레싱을 예방할 기준이 필요함
- 목표: 폴트율을 임계 이하로 유지하며 물리 프레임 내에서 다중 프로그래밍 정도를 최대화함

## Ⅱ. 구조 및 구성요소
선형 텍스트 구조도:
```
프로세스 참조열 -> 워킹셋 추적기: 최근 Δ 창의 서로 다른 페이지 집계
  -> WSS(Δ) 산출 -> 그만큼 프레임 보장
  -> Σ WSS > 물리 프레임? -> 예: 프로세스 suspend(MPL 하향)
                           -> 아니오: 유지
병행: PFF 제어기 -> 폴트율 측정
  -> 상한 초과: 프레임 추가 / 하한 미만: 프레임 회수
```

| 구성요소 | 역할 | 비고 |
| --- | --- | --- |
| 워킹셋 윈도우 Δ | 필요 페이지 판단 시간 범위 | 크기 튜닝 대상 |
| 워킹셋 추적기 | Δ 내 참조 페이지 집합 관리 | 참조비트·타이머 활용 |
| PFF 제어기 | 폴트율 상·하한으로 프레임 조절 | 워킹셋의 경량 대안 |
| suspend 큐 | 워킹셋 합 초과 시 내린 프로세스 보관 | MPL 하향 수단 |

> 요약: 워킹셋 추적기가 필요 프레임을 정하고, 초과 시 suspend로 MPL을 낮추며 PFF가 폴트율로 병행 조절함.

## Ⅲ. 동작원리 및 흐름도
선형 텍스트 흐름도:
```
참조 발생 -> 참조비트 세팅 -> 주기적 스캔으로 워킹셋 갱신
워킹셋 합 vs 프레임 -> 초과: 한 프로세스 suspend -> 여유 확보 후 재개
PFF: 폴트율 측정 -> 상한 초과: 프레임+ / 하한 미만: 프레임- / 정상: 유지
```
1. 각 참조가 페이지의 참조비트를 세팅하고, OS는 Δ 주기로 스캔해 프로세스별 워킹셋과 WSS를 갱신함.
2. 모든 프로세스의 WSS 합이 물리 프레임을 넘으면 OS가 한 프로세스를 suspend해 프레임을 회수함.
3. PFF 제어기는 프로세스의 폴트율을 측정해 상한 초과면 프레임을 추가하고 하한 미만이면 회수함.
4. 여유가 생기면 suspend된 프로세스를 재개해 다중 프로그래밍 정도를 안전 범위에서 회복함.

## Ⅳ. 특징
- 지역성을 정량화해 프로세스별 "필요 프레임"을 동적으로 산출함
- 워킹셋 합을 물리 프레임 이내로 강제해 스레싱을 근본적으로 예방함
- PFF는 집합 추적 없이 폴트율만 감시해 구현 오버헤드가 낮음
- 트레이드오프 — Δ·임계값 튜닝에 민감하고, 국면 전환기의 일시 폴트 급증을 오판할 여지가 있음

## Ⅴ. 심화 비교 및 적용 판단
워킹셋 모델과 PFF는 같은 목표(스레싱 예방)를 다른 방식으로 달성한다.

| 구분 | 워킹셋 모델 | PFF 방식 |
| --- | --- | --- |
| 판단 근거 | Δ 창의 참조 페이지 집합 직접 추적 | 폴트율 측정값(결과 지표) |
| 제어 방식 | WSS만큼 프레임 사전 보장 | 상·하한 피드백으로 사후 조절 |
| 오버헤드 | 참조 이력 추적 비용 큼 | 폴트 카운트만으로 경량 |
| 반응성 | 국면 변화에 선제적 | 폴트 발생 후 반응(지연) |
| 오판 위험 | Δ 부적정 시 과소·과대 | 국면 전환 스파이크 오인 |

> 요약: 정밀·선제 제어는 워킹셋, 경량·단순 구현은 PFF이며, 실무는 참조비트 근사와 폴트율 감시를 결합함.

- 리스크 — Δ 과소 설정 — 원인: 워킹셋 과소평가 — 대응: 폴트율 관측 기반 Δ 자동 조정
- 리스크 — 국면 전환기 오판 — 원인: 일시 폴트 급증 — 대응: 이동평균·히스테리시스로 스파이크 필터링
- 지표 — 페이지 폴트율(major fault) — 목표: 워크로드별 임계 이하 — 측정: `/proc/vmstat` pgmajfault·`sar -B`

## Ⅵ. 실무 적용 및 결론
- 적용 방안: 리눅스 cgroup v2의 `memory.high`·PSI(memory pressure)로 프로세스별 폴트 압력을 감시해 PFF와 유사하게 제어함
- 적용 방안: 컨테이너 메모리 request/limit를 워킹셋 실측(RSS·WSS)에 맞춰 산정해 노드 스레싱을 예방함
- 적용 방안: JVM 등 런타임의 힙 워킹셋을 프로파일링해 물리 메모리 초과 적재를 차단함
- 결론: 국면이 안정적이고 정밀 제어가 필요하면 워킹셋 실측 기반, 오버헤드·단순성이 중요하면 폴트율 피드백이 유리함
- 향후 방향: PSI·eBPF 기반 실시간 워킹셋 추정으로 컨테이너 오토스케일링과 연계해 선제 대응함
