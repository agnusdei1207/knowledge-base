## 미리 알고가기

- 형상 관리는 소프트웨어 산출물의 버전과 변경 이력을 통제하는 활동임
- Git은 대표적인 분산 버전 관리 시스템임
- 브랜치 전략은 협업과 릴리스 흐름을 구조화하는 규칙임

## Ⅰ. 개요

- **정의/개념**: 형상 관리는 코드와 문서와 빌드 산출물의 변경 이력과 버전과 승인 상태를 통제하는 활동이며, Git과 브랜치 전략은 이를 실무에서 구현하는 핵심 도구와 운영 규칙임
- **배경/필요성**: 다수 개발자가 동시에 작업하는 환경에서는 변경 충돌과 배포 혼선과 추적성 부족이 쉽게 발생하므로, 변경 단위와 병합 규칙과 릴리스 기준을 명확히 해야 함

## Ⅱ. 특징

- 분산 버전 관리로 로컬 작업과 병합 유연성이 높음
- 브랜치 전략이 배포 속도와 안정성에 직접 영향 줌
- 코드 리뷰와 CI와 결합될 때 형상 관리 가치가 커짐
- 전략만 복잡하고 팀 규율이 약하면 병합 비용이 더 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 trunk 기반 | 다중 브랜치 전략 |
|:---|:---|:---|
| 장점 | 빠른 통합과 단순성 | 릴리스 분리와 병행 작업 유리 |
| 한계 | 규율 부족 시 main 불안정 | 장기 브랜치 충돌 가능 |
| 적합 환경 | 자동화 성숙 조직 | 다중 버전 유지 조직 |
| 핵심 통제 | 작은 변경과 강한 CI | 병합 기준과 릴리스 관리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Repository | 소스와 이력과 협업 기준을 보관해 단일 진실 원천 역할을 함 |
| Branch Strategy | feature와 release와 hotfix 흐름을 정의해 병행 작업 충돌을 줄임 |
| Review and Merge Rule | 승인과 테스트 기준이 병합 품질과 배포 안정성을 좌우함 |
| Tag and Release Record | 특정 버전을 명확히 식별해 배포 추적성과 롤백 가능성을 높임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변경 분기 생성  | --> | 개발/커밋      | --> | 리뷰/병합      | --> | 태그/릴리스 관리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변경 분기 생성**: 작업 목적에 맞는 브랜치를 만듦
2. **개발 및 커밋**: 작은 단위로 이력을 남김
3. **리뷰 및 병합**: 승인과 테스트를 거쳐 기준 브랜치에 합침
4. **태그 및 릴리스 관리**: 버전을 고정하고 배포 기준을 남김

## Ⅵ. 문제점 및 해결 방안

1. 문제: 장기 브랜치를 오래 유지하면 병합 충돌과 숨은 결함이 누적될 수 있음
   - 해결방안: 작은 단위 통합과 짧은 생명주기를 운영하고 merge conflict rate와 branch lifetime으로 검증함
2. 문제: 브랜치 전략이 팀 규모와 자동화 수준에 맞지 않으면 규칙만 많고 실제 흐름은 느려질 수 있음
   - 해결방안: 팀 상황에 맞는 최소 전략을 채택하고 review lead time과 release predictability로 검증함
3. 문제: 태그와 릴리스 기록이 부실하면 배포 추적과 롤백 근거가 불명확해질 수 있음
   - 해결방안: release artifact trace를 표준화하고 rollback readiness score와 traceability coverage로 검증함

## Ⅶ. 적용 사례

- SaaS 제품팀에서는 trunk 기반 전략을 사용하고, branch lifetime과 review lead time로 결과를 확인함
- 다중 버전 유지 조직에서는 release branch를 운영하고, release predictability와 rollback readiness score로 결과를 확인함
- 규제형 프로젝트에서는 릴리스 기록을 강화하고, traceability coverage와 merge conflict rate로 결과를 확인함

## Ⅷ. 결론

형상 관리의 핵심은 Git 명령 사용이 아니라 변경이 언제 어떤 기준으로 합쳐지고 배포 가능한 상태가 되는지 조직적으로 통제하는 데 있음.
