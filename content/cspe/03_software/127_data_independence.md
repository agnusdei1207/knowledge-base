## 미리 알고가기

- 데이터 독립성은 데이터 구조 변경이 상위 사용자 관점에 미치는 영향을 최소화하는 원리임
- 논리적 독립성과 물리적 독립성으로 나뉨
- 3단계 스키마 구조와 함께 이해하면 개념이 명확해짐

## Ⅰ. 개요

- **정의/개념**: 데이터 독립성은 저장 방식이나 논리 구조가 바뀌더라도 상위 응용 프로그램과 사용자 관점이 최대한 영향을 받지 않도록 데이터 표현 계층을 분리하는 데이터베이스 설계 원리임
- **배경/필요성**: 시스템이 커질수록 성능 개선과 업무 변화에 따라 스키마와 저장 구조가 자주 바뀌므로, 변경 파급을 줄이는 추상화가 필요함

## Ⅱ. 특징

- 물리적 독립성은 저장 구조 변경이 논리 스키마에 미치는 영향을 줄임
- 논리적 독립성은 논리 스키마 변경이 외부 뷰와 프로그램에 미치는 영향을 줄임
- 완전한 독립성은 어렵지만 변경 파급을 줄이는 방향이 중요함
- 독립성이 약하면 작은 스키마 변경도 다수 프로그램 수정으로 이어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리적 독립성 | 논리적 독립성 |
|:---|:---|:---|
| 변경 대상 | 저장 구조와 접근 경로 | 테이블 구조와 관계 |
| 보호 대상 | 개념 스키마와 응용 프로그램 | 외부 뷰와 사용자 프로그램 |
| 대표 예 | 인덱스 추가·파일 재조직 | 속성 추가·테이블 분리 |
| 구현 난도 | 상대적으로 쉬움 | 상대적으로 어려움 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| External View | 사용자와 프로그램별 필요한 데이터 표현을 제공함 |
| Conceptual Schema | 조직 전체 데이터 의미와 관계를 통합적으로 정의함 |
| Internal Schema | 실제 파일 구조와 인덱스와 저장 방식을 다룸 |
| Mapping Rule | 계층 간 매핑을 통해 변경 영향을 흡수함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변경 요구 발생   | --> | 영향 계층 식별  | --> | 매핑 조정      | --> | 프로그램 영향 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변경 요구 발생**: 저장 방식 또는 논리 구조 변경이 필요해짐
2. **영향 계층 식별**: 물리 변경인지 논리 변경인지 구분함
3. **매핑 조정**: 상위 계층 영향이 최소화되도록 조정함
4. **프로그램 영향 검증**: 뷰와 응용 프로그램 호환성을 확인함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 데이터 독립성을 고려하지 않고 프로그램이 물리 구조에 직접 의존하면 튜닝조차 대규모 수정으로 이어질 수 있음
   - 해결방안: abstraction layer와 view 사용을 강화하고 direct storage dependency count와 change ripple rate로 검증함
2. 문제: 논리 스키마 변경 시 외부 뷰 관리가 부실하면 다수 서비스가 동시에 깨질 수 있음
   - 해결방안: schema compatibility review를 운영하고 backward compatibility rate와 consumer breakage count로 검증함
3. 문제: 독립성 원칙을 문서화하지 않으면 개발 조직이 단기 편의로 계층 경계를 계속 침범할 수 있음
   - 해결방안: data contract governance를 적용하고 contract compliance rate와 unauthorized coupling count로 검증함

## Ⅶ. 적용 사례

- 운영 DB 성능 튜닝에서는 추상 계층을 유지하고 확인 지표는 direct storage dependency count와 change ripple rate임
- 스키마 진화가 잦은 SaaS에서는 호환성 리뷰를 운영하고 확인 지표는 backward compatibility rate와 consumer breakage count임
- 데이터 플랫폼 조직에서는 계약 거버넌스를 적용하고 확인 지표는 contract compliance rate와 unauthorized coupling count임

## Ⅷ. 결론

데이터 독립성은 이론적 분류가 아니라 구조 변경을 서비스 중단 없이 흡수하기 위한 데이터베이스 추상화 원칙임.
