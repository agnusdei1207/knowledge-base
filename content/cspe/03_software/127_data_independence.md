## 미리 알고가기

- 외부 스키마는 사용자·응용별 데이터 표현, 개념 스키마는 전체 논리 구조, 내부 스키마는 물리 저장 구조임
- 물리적 독립성은 내부 스키마 변경이 개념·외부 스키마와 응용 프로그램에 영향을 주지 않는 성질임
- 논리적 독립성은 개념 스키마 변경을 외부 스키마·응용 프로그램 변경 없이 수용하는 성질임
- 외부-개념 매핑과 개념-내부 매핑이 계층 간 구조 차이를 변환함

## 작성 근거(검토용)

- 데이터 독립성은 변경 계층, 보호 계층, 매핑 수단, 대표 변경, 상위 계층 영향을 핵심 비교축으로 설명함
- 3단계 스키마와 두 매핑이 독립성을 만드는 정적 구조이므로 이를 반복하는 일반 변경 절차 Ⅴ절은 삭제함
- 실무 사례는 인덱스·파티션 변경과 호환 뷰를 응용 SQL 변경 건수·회귀 오류로 검증함

## Ⅰ. 개요

- **정의/개념**: 데이터 독립성은 내부·개념 스키마의 변경을 계층 간 매핑에서 흡수해 상위 스키마와 응용 프로그램의 변경을 제한하는 3단계 스키마 성질임
- **배경/필요성**: 저장 성능 튜닝과 업무 모델 변경이 응용 SQL·화면 계약의 연쇄 수정으로 이어지지 않도록 스키마 계층과 매핑 구조가 필요함

## Ⅱ. 특징

- 물리적 독립성은 인덱스·파일·파티션 변경을 개념-내부 매핑에서 흡수함
- 논리적 독립성은 테이블·속성·관계 변경을 외부-개념 매핑과 호환 뷰에서 흡수함
- 외부 스키마를 사용자·응용별로 분리해 같은 개념 데이터에 서로 다른 표현을 제공함
- 논리 구조 변경은 외부 질의 의미까지 바꿀 수 있어 저장 구조 변경보다 독립성 확보가 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리적 독립성 | 논리적 독립성 |
|:---|:---|:---|
| 변경 계층 | 내부 스키마 | 개념 스키마 |
| 변경 대상 | 파일 조직·인덱스·파티션·저장 위치 | 테이블·속성·관계·제약 |
| 보호 계층 | 개념·외부 스키마와 응용 SQL | 외부 스키마와 응용 계약 |
| 흡수 수단 | 개념-내부 매핑·옵티마이저·저장 엔진 | 외부-개념 매핑·호환 뷰·스키마 버전 |
| 대표 변경 | 인덱스 추가·파일 재배치·파티션 분할 | 컬럼 추가·테이블 분리·관계 재구성 |
| 상위 계층 영향 | 접근 경로가 바뀌어도 개념 데이터의 의미를 유지 | 개체·관계 변경이 외부 질의 의미와 응용 계약에 영향 |

> 요약: 물리적 독립성은 내부 저장 변경을, 논리적 독립성은 개념 구조 변경을 매핑에서 흡수해 상위 계층을 보호함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 스키마 | 사용자·응용별 뷰와 데이터 표현을 정의함 |
| 외부-개념 매핑 | 외부 표현을 개념 구조에 연결하고 논리 변경을 변환함 |
| 개념 스키마 | 전체 데이터 개체·관계·제약을 논리적으로 정의함 |
| 개념-내부 매핑 | 개념 구조를 파일·인덱스·파티션 경로에 연결함 |
| 내부 스키마 | 레코드 배치·접근 경로·저장 위치를 정의함 |

```text
+-----------+      +-----------+      +-----------+
| 외부 스키마 | <--> | 개념 스키마 | <--> | 내부 스키마 |
+-----------+      +-----------+      +-----------+
      외부-개념 매핑         개념-내부 매핑
```

> 요약: 두 매핑은 외부 표현·개념 구조·내부 저장의 차이를 변환해 하위 계층 변경이 상위 계층으로 전파되는 범위를 제한함.

## Ⅵ. 실무 사례

1. 운영 DB는 인덱스·파티션을 변경하고 응용 SQL 변경 건수·p95 질의 지연을 확인함
2. 주문 스키마 분리는 호환 뷰와 스키마 버전을 적용하고 영향받은 질의 수·회귀 오류 건수를 확인함

## Ⅶ. 결론

- 데이터 독립성은 변경 계층과 보호 계층을 구분하고 두 매핑이 흡수할 응용 변경 범위를 기준으로 설계해야 함
