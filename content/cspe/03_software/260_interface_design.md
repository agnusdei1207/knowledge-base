## Ⅰ. 개요
- 정의: 시스템/컴포넌트 간 상호작용 규격 정의 및 언어 독립적 기술 기법(IDL)
- 배경: 이기종 시스템 통합 및 분산 환경에서의 통신 규격 표준화 필요
- 출제 의도: 인터페이스 설계 원칙 및 IDL(Interface Definition Language) 활용 이해

## Ⅱ. 구성요소
- 구조도
  [Client] --(IDL Definition)--> [Server]
  Stub <--- [Network] ---> Skeleton

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| IDL | 플랫폼 독립적 인터페이스 기술 언어 | 통역사(Standard) |
| 시그니처 | 메서드 명, 파라미터, 반환값 규격 | 명함/계약서 |
| Marshalling | 데이터를 전송 형식으로 변환 | 이삿짐 포장 |
> 요약: 구현 상세를 숨기고 외부 노출 기능만을 표준 형식으로 정의함

## Ⅲ. 절차
- 흐름도
  서비스 식별 -> 규격 정의 -> IDL 작성 -> 코드 생성
- 4단계 설명
1. 서비스 식별: 외부 제공이 필요한 핵심 기능 및 데이터 요건 파악
2. 규격 정의: 통신 방식(Sync/Async), 데이터 타입, 예외 처리 설계
3. IDL 작성: gRPC(Proto), OpenAPI(Swagger) 등으로 규격 명세화
4. 코드 생성: IDL 컴파일러를 통한 언어별 클라이언트/서버 스켈레톤 생성
> 요약: 규격 선정의 표준화를 통해 개발 생산성 및 상호운용성 증대

## Ⅳ. 문제점
- 인터페이스 변경 시 관련 모든 시스템의 재배포/수정 필요 (Tight Coupling)
- 과도하게 복잡한 데이터 구조 전송 시 직렬화 오버헤드 및 성능 저하

## Ⅴ. 개선방안
- 하위 호환성 유지(Versioning) 전략 수립 및 변경 영향도 분석 자동화
- 가벼운 데이터 형식(JSON/Protobuf) 사용 및 비동기 통신 도입으로 성능 최적화

## Ⅵ. 전망
- 클라우드 네이티브 환경에서 gRPC, GraphQL 등 고성능 인터페이스 기술 확산
- CSF: API First Design 전략 기반의 인터페이스 거버넌스 체계 구축
