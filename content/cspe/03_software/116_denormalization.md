## Ⅰ. 개요
- **정의**: 정규화된 릴레이션에 의도적 중복·통합을 적용하여 조회 성능을 향상시키는 기법임
- **배경/필요성**: 정규화(115 참조)로 조인이 과다해지면 응답 시간이 증가하여 서비스 품질 저하됨
- **비유**: 자주 쓰는 물건을 여러 방에 복사본으로 두어 꺼내러 가는 횟수를 줄이는 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규화와의 트레이드오프 이해 | 테이블/컬럼/관계 반정규화 유형 구분 | 무조건 적용이 아닌 성능 측정 근거 필요 |

> 요약: 정규화의 조인 부하를 줄이기 위해 의도적 중복을 허용하는 성능 최적화 기법임

## Ⅱ. 구성요소
```text
Denormalization
 +-- Table Merge -------- 1:1/1:N 테이블 통합
 +-- Table Split -------- 수직/수평 분할
 +-- Column Redundancy --- 파생/중복 컬럼 추가
 +-- Derived Table ------- 집계/통계 테이블 생성
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 테이블 통합 | 조인 빈도 높은 1:1/1:N 테이블을 하나로 합침 | 두 서랍을 하나로 |
| 컬럼 중복 | 자주 참조하는 속성을 다른 테이블에 복사 | 복사본 비치 |
| 파생 테이블 | 집계 결과를 미리 계산하여 별도 테이블로 보관 | 요약 대시보드 |

> 요약: 통합, 분할, 중복, 파생의 4가지 유형으로 조회 성능을 확보함

## Ⅲ. 절차
```text
성능 분석 --> 병목 식별 --> 반정규화 적용 --> 정합성 보완
```
- 1단계: 조회 패턴·응답 시간 분석으로 성능 기준 미달 구간 확인
- 2단계: 조인 횟수·테이블 크기 기준으로 병목 릴레이션 식별
- 3단계: 테이블 통합·컬럼 추가·파생 테이블 중 적합한 유형 적용
- 4단계: 트리거·배치를 통해 중복 데이터의 정합성 유지 메커니즘 구현

> 요약: 분석-식별-적용-보완 4단계로 성능과 정합성을 동시에 관리함

## Ⅳ. 문제점
- 데이터 불일치: 중복 데이터 갱신 누락 시 원본과 복사본 간 불일치 발생
- 저장 공간 증가: 중복·파생 데이터로 인해 디스크 사용량 증가
- 갱신 성능 저하: 중복 컬럼 동기화를 위한 추가 쓰기 연산 발생

> 요약: 불일치, 저장 비용, 쓰기 부하가 반정규화의 부작용임

## Ⅴ. 개선방안
1. 단기: 트리거·Application 레벨 동기화로 중복 데이터 정합성 보장
2. 중기: 파티셔닝·압축 기법으로 저장 공간 증가 완화
3. 장기: Materialized View 등 DBMS 기능으로 수동 중복 관리 대체

> 요약: 동기화 자동화, 압축, DBMS 내장 기능으로 부작용을 통제함

## Ⅵ. 전망
- 발전 방향: 인메모리 DB·컬럼스토어에서는 반정규화 필요성이 감소하는 추세임
- 기술사적 판단: OLTP에서는 최소한의 선별 적용, OLAP에서는 적극 활용이 원칙임
- 기술사 제언: 반정규화는 성능 측정 데이터 기반으로 판단하고 문서화할 필요
