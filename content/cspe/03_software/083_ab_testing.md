## Ⅰ. 개요
- **정의**: 두 가지 이상의 변형을 실제 사용자에게 무작위 배정해 통계적으로 우열을 판별하는 실험 기법
- **배경/필요성**: 의사결정을 직관 대신 데이터 기반으로 수행해야 비즈니스 지표 개선을 검증할 수 있음
- **비유**: 같은 약을 복용·미복용 그룹으로 나눠 효과를 비교하는 임상시험

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 통계적 가설 검정 기반 의사결정 | 대조군-실험군 분리, p-value, 표본 크기 산정 | Canary 배포(082)와 목적 차이를 구분할 것 |

> 요약: 대조군·실험군 비교를 통해 기능 변경의 효과를 통계적으로 검증하는 기법임

## Ⅱ. 구성요소
```text
User Pool --> Random Assign --> Group A (Control)
                           +--> Group B (Variant)
Group A/B --> Metric Collector --> Statistical Engine --> Decision
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Random Assigner | 사용자를 대조군·실험군에 균등 무작위 배정하는 모듈 | 제비뽑기 |
| Metric Collector | 전환율·클릭률 등 목표 지표를 수집하는 파이프라인 | 설문 수거함 |
| Statistical Engine | p-value·신뢰구간을 산출해 유의미한 차이를 판정하는 엔진 | 심판 |

> 요약: 무작위 배정-지표 수집-통계 판정 3요소로 실험을 수행함

## Ⅲ. 절차
```text
가설 수립 --> 실험 설계 --> 트래픽 분배·수집 --> 결과 분석·적용
```
- 1단계: 가설 수립—"변형 B가 전환율을 X % 이상 개선한다"는 귀무·대립가설 정의
- 2단계: 실험 설계—필요 표본 크기, 실험 기간, 유의수준(α) 사전 결정
- 3단계: 트래픽 분배·수집—사용자를 무작위 배정 후 목표 지표를 수집
- 4단계: 결과 분석·적용—p-value < α이면 대립가설 채택, 아니면 귀무가설 유지

> 요약: 가설-설계-수집-분석 4단계로 데이터 기반 의사결정을 수행함

## Ⅳ. 문제점
- 표본 오염: 동일 사용자가 양쪽 그룹에 노출되면 실험 결과가 왜곡됨
- 조기 종료 오류: 표본 미달 상태에서 중간 결과로 판단 시 1종 오류 확률이 증가함
- 다변량 교호 작용: 복수 변형 동시 실험 시 변형 간 상호 영향을 분리하기 곤란함

> 요약: 표본 오염, 조기 종료, 교호 작용이 실험 신뢰도를 저해함

## Ⅴ. 개선방안
1. 단기: 사용자 ID 해시 기반 고정 배정으로 그룹 누출 방지
2. 중기: Sequential Testing 기법 적용으로 중간 분석 시에도 오류율을 보정
3. 장기: 베이지안 다변량 밴딧(Multi-Armed Bandit) 도입으로 교호 작용을 실시간 분리

> 요약: 고정 배정-순차 검정-베이지안 밴딧 순으로 실험 정확도를 향상시킴

## Ⅵ. 전망
- 발전 방향: ML 기반 자동 가설 생성·자동 트래픽 최적 배분으로 실험 자동화 확대
- 기술사적 판단: Feature Flag(081)와 결합해 실험-릴리스를 일원화하는 추세임
- 기술사 제언: 실험 거버넌스(윤리·개인정보 동의·실험 등록부) 체계를 조직 차원에서 수립할 필요
