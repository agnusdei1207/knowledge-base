## 미리 알고가기

- 12 팩터 앱은 클라우드 환경에 맞는 애플리케이션 운영 원칙 모음임
- Stateless process는 프로세스 안에 세션이나 파일 상태를 두지 않는 실행 방식임
- Build, release, run 분리는 빌드 산출물과 배포 버전과 실행 단계를 나눠 관리하는 원칙임

## 작성 근거(검토용)

- 12 팩터 앱은 설정, 상태, 배포 산출물, 로그 처리 방식을 핵심 비교축으로 선정함
- 구성은 환경 독립성과 수평 확장을 만드는 운영 원칙을 중심으로 제시함
- 실무 판단은 무중단 교체 성공률, 설정 불일치 건수, 배포 롤백률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 12 팩터 앱은 애플리케이션의 빌드·배포·확장을 위해 코드·설정·상태·로그를 분리하는 클라우드 운영 원칙임
- **배경/필요성**: 다중 환경 배포와 수평 확장 과정에서 환경 의존성을 줄이고 같은 산출물을 재현 가능하게 실행할 기준이 필요함

## Ⅱ. 특징

- 설정과 코드를 분리해 환경별 설정값을 관리함
- 세션·파일 상태를 외부 backing service에 저장해 인스턴스 교체와 수평 확장 시 로컬 상태 이전을 없앰
- 빌드와 릴리스와 실행 단계를 나눠 배포 추적성과 재현성을 높임
- 레거시 구조나 상태 저장 방식이 강한 시스템에는 그대로 적용하기 어려울 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 서버형 애플리케이션 | 12 팩터 앱 |
|:---|:---|:---|
| 설정 관리 | 코드나 서버 파일 안에 설정이 섞여 있는 경우가 많음 | 설정을 환경 변수나 외부 비밀 저장소로 분리함 |
| 상태 관리 | 세션이나 파일 상태를 로컬 인스턴스에 두기 쉬움 | 프로세스를 stateless하게 유지하고 외부 저장소를 사용함 |
| 배포 방식 | 서버별 수작업과 환경별 차이가 생기기 쉬움 | 반복 가능한 자동 배포와 동일한 릴리스 흐름을 지향함 |
| 로그 처리 | 로컬 파일에 남기고 서버에서 직접 확인하는 경우가 많음 | 로그를 이벤트 스트림처럼 수집해 중앙에서 분석함 |

> 요약: 12 팩터 앱은 설정·상태·배포 산출물·로그를 분리해 환경 전환과 인스턴스 교체를 가능하게 함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 설정 분리 | 설정을 코드에서 분리해 환경별 값을 관리함 |
| 무상태 프로세스 | 지속 상태를 외부 서비스에 저장해 인스턴스를 교체·증설함 |
| 빌드·릴리스·실행 분리 | 빌드 산출물과 환경 설정과 실행 단계를 나눠 배포 버전을 추적함 |
| 로그 스트림 | 로그를 이벤트 스트림으로 출력해 중앙 수집·분석함 |

> 요약: 코드와 설정을 분리하고 같은 빌드 산출물을 무상태 프로세스로 실행하며 로그를 외부로 전달함.

## Ⅵ. 실무 사례

1. 클라우드 웹서비스는 세션·파일을 외부 저장소로 분리하고 무중단 교체 성공률을 확인함
2. 배포 플랫폼은 설정·비밀값을 외부화하고 설정 불일치 건수·배포 롤백률을 확인함

## Ⅶ. 결론

12 팩터 앱은 애플리케이션을 특정 서버와 분리해 반복 배포와 수평 확장을 지원하는 운영 원칙임
