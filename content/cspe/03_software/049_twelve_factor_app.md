## 미리 알고가기

- 12 팩터 앱(12 Factor App): 클라우드 플랫폼(SaaS)에 최적화된 이식성과 확장성이 높은 애플리케이션을 구축하기 위한 12가지 설계 원칙임
- 무상태 프로세스(Stateless Process): 서버 메모리나 로컬 디스크에 영구적인 상태를 남기지 않고 독립 실행되는 프로세스임
- 빌드·릴리스·실행(Build, Release, Run): 소스 코드를 실행 파일로 변환(Build), 설정값 결합(Release), 프로세스로 구동(Run)하는 단계를 엄격히 격리하는 원칙임
- 지원 서비스(Backing Service): 데이터베이스, 캐시 등 네트워크를 통해 통신하는 외부 의존 인프라 자원임
- 환경 일치(Dev/Prod Parity): 개발, 스테이징, 운영 환경의 격차(시간, 사람, 도구)를 최소화하여 재현성을 확보하는 원칙임
- 포트 바인딩(Port Binding): 별도의 웹 서버 컨테이너 없이 스스로 특정 포트를 열어 외부에 서비스를 노출하는 방식임

## 작성 근거(검토용)

- 12 팩터 앱은 설정, 상태, 배포 산출물, 로그 처리 방식을 핵심 비교축으로 선정함
- 구성은 환경 독립성과 수평 확장을 만드는 운영 원칙을 중심으로 제시함
- 실무 판단은 무중단 교체 성공률, 설정 불일치 건수, 배포 롤백률로 구체화함
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정함.

## Ⅰ. 개요

- **정의/개념**: 12 팩터 앱은 애플리케이션의 빌드·배포·확장을 위해 코드·설정·상태·로그를 분리하는 클라우드 운영 원칙임
- **배경/필요성**: 다중 환경 배포와 수평 확장 과정에서 환경 의존성을 줄이고 같은 산출물을 재현 가능하게 실행할 기준이 필요함

### 쉽게 이해하기 (학습용)
- 렌터카를 탈 때 내 짐을 차에 붙여두지 않고 가방에 넣어 가지고 다니다가 차가 고장 나면 바로 다른 차로 갈아타는 것처럼, 클라우드에서 앱을 쉽게 바꾸고 확장하는 규칙임.

## Ⅱ. 특징

- 설정과 코드를 분리해 환경별 설정값을 관리함
- 세션·파일 상태를 외부 backing service에 저장해 인스턴스 교체와 수평 확장 시 로컬 상태 이전을 없앰
- 빌드와 릴리스와 실행 단계를 나눠 배포 추적성과 재현성을 높임
- 레거시 구조나 상태 저장 방식이 강한 시스템에는 그대로 적용하기 어려울 수 있음

### 쉽게 이해하기 (학습용)
- 실행 프로그램과 비밀번호 설정(환경 변수)을 따로 두고, 데이터는 모두 외부에 두어 서버가 갑자기 꺼져도 정보 유실 없이 즉시 새 서버를 띄울 수 있음.

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 서버형 애플리케이션 | 12 팩터 앱 |
|:---|:---|:---|
| 설정 및 상태 관리 | 소스 코드에 설정값을 내장하며 로컬 세션·디스크에 파일 등 상태를 보관함 | 설정을 환경 변수로 관리하며 상태는 외부의 무상태($Stateless$) 저장소에 분리함 |
| 배포 및 실행 독립성 | 빌드와 설정 반영이 수작업으로 섞여 진행되며 환경 간 재현성이 낮음 | 빌드·릴리스·실행 단계를 물리적으로 격리하여 반복 가능한 배포를 실현함 |
| 로그 및 모니터링 | 로컬 서버 파일에 로그를 기록하여 별도 로그 뷰어로 파싱함 | 로그를 표준 출력($stdout$) 스트림으로 취급하여 실시간 중앙 수집기로 위임함 |

> 요약: 12 팩터 앱은 설정·상태·배포 산출물·로그를 분리해 환경 전환과 인스턴스 교체를 가능하게 함.

### 쉽게 이해하기 (학습용)
- 서버 컴퓨터 한 대에 모든 것을 넣고 수동으로 설정하는 이전 방식과 달리, 모든 규칙을 자동화하고 부품을 분리하여 클라우드에 맞춤 조립하는 현대식 방식의 대조임.

## Ⅳ. 설계 요소 및 구조

```text
[코드베이스] ───(환경변수 설정 결합)───> [빌드·릴리스·실행] ───> [무상태 프로세스]
    │                                                                  │
    └───────────(네트워크 통신 포트 바인딩)────────────────────────────┴──> [지원 서비스]
```

| 설계 요소 | 설명 |
|:---|:---|
| 코드베이스 & 설정 | 단일 코드베이스로 버전 관리하며, 환경별 설정은 환경 변수로 코드와 완전히 분리함 |
| 빌드·릴리스·실행 | 코드 빌드, 설정 결합(릴리스), 프로세스 구동(실행) 단계를 엄격히 분리하여 운영함 |
| 무상태 프로세스 | 실행 환경의 공유 상태를 배제하고 영구 상태는 Backing Service에 위임함 |
| 포트 바인딩 & 동시성 | 스스로 웹 서버를 내장해 포트를 열고, 무상태 프로세스를 복제하여 수평 확장함 |

> 요약: 코드와 설정을 분리하고 같은 빌드 산출물을 무상태 프로세스로 실행하며 로그를 외부로 전달함.

### 쉽게 이해하기 (학습용)
- 소스 코드 관리창(코드베이스), 프로그램 조립기(빌드·릴리스), 무상태 엔진(프로세스), 외장 저장소(지원 서비스)가 맞물려 돌아가는 분리형 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
소스 코드 작성 ──> 빌드 단계 (패키징) ──> 릴리스 단계 (설정 결합) ──> 실행 단계 (구동)
```

1. **소스 코드 작성**: 버전 관리 시스템에 단일 코드베이스를 유지하고 코드를 관리함
2. **빌드 단계**: 코드를 실행 가능한 바이너리 또는 패키지로 변환하고 라이브러리 의존성을 결합함
3. **릴리스 단계**: 빌드 산출물과 현재 실행 환경의 설정(환경 변수)을 결합하여 고유 릴리스 버전을 생성함
4. **실행 단계**: 릴리스 버전을 실행 엔진을 통해 무상태 프로세스로 구동하며 외부 리소스와 연결함

> 요약: 소스 코드를 패키징한 후 환경 설정을 결합해 릴리스 버전을 만들고, 이를 무상태 프로세스로 분리 실행함.

### 쉽게 이해하기 (학습용)
- 소스 코드를 기계어로 굽고(빌드), 거기에 설정 파일(비밀번호 등)을 입히고(릴리스), 최종 패키지를 실행 엔진으로 깨워 가동시키는 순서로 배포가 일어남.

## Ⅵ. 실무 사례

쿠버네티스(Kubernetes) 기반 컨테이너 오케스트레이션 환경에서 애플리케이션의 세션 정보를 내장 Redis로 외재화하고 로그를 표준 출력으로 스트림 처리하여 수평 확장성과 이식성을 극대화함. 환경별 데이터베이스 접속 정보 및 API 키는 코드에 노출하지 않고 컨테이너 내부의 환경 변수와 Secret 객체로 바인딩하여 안전하게 주입함.

### 쉽게 이해하기 (학습용)
- 클라우드 서버에서 앱이 갑자기 늘어날 때(오토스케일링), 로그인 정보가 사라지지 않도록 전용 캐시 서버에 로그인 정보를 몰아놓고 실행 서버는 계속 늘렸다 줄였다 함.

## Ⅶ. 결론

- 12 팩터 앱은 클라우드 가상화 및 컨테이너 환경에서 애플리케이션의 독립성, 확장성, 배포 재현성을 보장하는 핵심 아키텍처 원칙임.
- 무상태 및 외부화 원칙을 설계 초기부터 강제하여 로컬 상태 지향적인 레거시 코드로 인한 의존성 결합을 사전에 방지해야 함.

### 쉽게 이해하기 (학습용)
- 이 규칙은 클라우드 시대에 반드시 지켜야 할 프로그램 설계 표준이며, 서버 안에 고유한 정보를 숨겨두지 않는 습관을 들여 확장성을 확보하는 것이 중요함.
