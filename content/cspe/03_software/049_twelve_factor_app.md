## 미리 알고가기

- 12 팩터 앱은 클라우드 환경에 맞는 애플리케이션 운영 원칙 모음임
- Stateless process는 프로세스 안에 세션이나 파일 상태를 두지 않는 실행 방식임
- Build, release, run 분리는 빌드 산출물과 배포 버전과 실행 단계를 나눠 관리하는 원칙임

## Ⅰ. 개요

- **정의/개념**: 12 팩터 앱은 클라우드와 PaaS 환경에서 애플리케이션을 일관되게 빌드, 배포, 확장하기 위해 코드, 설정, 의존성, 프로세스, 로그를 분리 관리하는 운영 원칙 집합임.
- **배경/필요성**: 현대 서비스는 다중 환경 배포와 수평 확장과 자동 복구를 반복하므로, 환경 의존성을 줄이고 배포 재현성을 높이는 공통 실행 규율이 필요함.

## Ⅱ. 특징

- 설정과 코드를 분리해 환경별 차이를 안전하게 관리함
- 세션·파일 상태를 외부 backing service에 저장해 인스턴스 교체와 수평 확장 시 로컬 상태 이전을 없앰
- 빌드와 릴리스와 실행 단계를 나눠 배포 추적성과 재현성을 높임
- 레거시 구조나 상태 저장 방식이 강한 시스템에는 그대로 적용하기 어려울 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 전통 서버형 애플리케이션 | 12 팩터 앱 |
|:---|:---|:---|
| 설정 관리 | 코드나 서버 파일 안에 설정이 섞여 있는 경우가 많음 | 설정을 환경 변수나 외부 비밀 저장소로 분리함 |
| 상태 관리 | 세션이나 파일 상태를 로컬 인스턴스에 두기 쉬움 | 프로세스를 stateless하게 유지하고 외부 저장소를 사용함 |
| 배포 방식 | 서버별 수작업과 환경별 차이가 생기기 쉬움 | 반복 가능한 자동 배포와 동일한 릴리스 흐름을 지향함 |
| 로그 처리 | 로컬 파일에 남기고 서버에서 직접 확인하는 경우가 많음 | 로그를 이벤트 스트림처럼 수집해 중앙에서 분석함 |

> 요약: 12 팩터 앱은 설정·의존성·빌드·실행·로그를 분리해 환경별 배포와 인스턴스 교체 절차를 일관되게 만드는 실행 규율임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Config Separation | 설정을 코드에서 분리해 환경 간 차이를 안전하게 관리하게 함 |
| Stateless Process | 지속 상태를 backing service에 저장해 인스턴스를 독립 교체·증설함 |
| Build Release Run Split | 빌드 산출물과 배포 버전과 실행 단계를 나눠 추적성과 재현성을 높임 |
| Log Stream Model | 로그를 파일이 아니라 수집 대상 이벤트로 다뤄 중앙 분석을 단순화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드/설정 분리  | --> | 빌드/릴리스 분리 | --> | stateless 실행 | --> | 로그/확장 운영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드와 설정 분리**: 환경별 설정을 외부화함
2. **빌드와 릴리스 분리**: 배포 가능한 아티팩트와 환경 반영 시점을 구분함
3. **Stateless 실행**: 프로세스를 쉽게 교체 가능한 단위로 운영함
4. **로그와 확장 운영**: 로그를 중앙 수집하고 인스턴스를 수평 확장함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 네이티브 웹앱에서는 12 팩터 원칙이 배포 표준화에 유리하지만 로컬 파일과 세션 상태에 의존하면 무중단 교체가 어렵므로 외부 저장소와 세션 분리를 적용하고 무상태 원칙 준수율과 배포 성공률로 확인함
2. 플랫폼 팀이 공통 템플릿을 제공하는 환경에서는 설정 외부화와 비밀 관리가 핵심이므로 설정 형상관리와 비밀 관리 체계를 함께 운영하고 설정 불일치 건수와 배포 롤백 비율로 확인함

## Ⅶ. 결론

12 팩터 앱은 애플리케이션을 특정 서버에 묶지 않고 반복 배포와 수평 확장에 맞추기 위한 운영 원칙임.
