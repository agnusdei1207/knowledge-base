## 미리 알고가기

- 12 Factor App은 클라우드 친화적 애플리케이션 운영 원칙 모음임
- 코드와 설정과 로그와 프로세스 생명주기를 분리 관리하는 것이 핵심임
- 단순 개발 지침이 아니라 배포와 운영 모델까지 포함함

## Ⅰ. 개요

- **정의/개념**: 12 팩터 앱은 클라우드와 PaaS 환경에서 애플리케이션을 일관되게 빌드하고 배포하고 확장하기 위해 코드베이스와 설정과 의존성과 프로세스와 로그를 분리 관리하는 운영 원칙 집합임
- **배경/필요성**: 현대 서비스는 다중 환경 배포와 수평 확장과 자동 복구를 반복하므로, 환경 의존성을 줄이고 배포 가능성을 높이는 공통 규율이 필요함

## Ⅱ. 특징

- 설정과 코드를 분리해 환경별 변경을 단순화함
- 프로세스를 stateless하게 유지해 수평 확장과 재시작을 쉽게 만듦
- 빌드와 릴리스와 실행 단계를 구분해 배포 추적성을 높임
- 전통 레거시 시스템에는 그대로 적용하기 어려운 항목도 존재함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 서버형 애플리케이션 | 12 Factor App |
|:---|:---|:---|
| 설정 관리 | 코드나 파일에 혼재 | 환경 변수와 외부 설정 분리 |
| 상태 관리 | 로컬 상태 의존 가능 | stateless 프로세스 지향 |
| 배포 구조 | 서버별 수작업 가능 | 자동화와 반복 배포 중심 |
| 로그 처리 | 로컬 파일 중심 | 이벤트 스트림처럼 수집 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Config Separation | 설정을 코드에서 분리해 환경 간 차이를 안전하게 관리하게 함 |
| Stateless Process | 프로세스 자체에 세션이나 파일 상태를 두지 않아 확장과 교체를 쉽게 만듦 |
| Build Release Run Split | 빌드 산출물과 배포 버전과 실행 단계를 나눠 추적성과 재현성을 높임 |
| Log Stream Model | 로그를 파일이 아니라 이벤트 스트림으로 취급해 중앙 수집과 분석을 단순화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드/설정 분리  | --> | 빌드/릴리스 분리 | --> | stateless 실행 | --> | 로그/확장 운영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드와 설정 분리**: 환경별 설정을 외부화함
2. **빌드와 릴리스 분리**: 배포 가능한 아티팩트와 환경 투입 시점을 구분함
3. **stateless 실행**: 프로세스를 쉽게 교체 가능한 단위로 운용함
4. **로그와 확장 운영**: 로그를 중앙화하고 인스턴스를 수평 확장함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 애플리케이션이 로컬 파일과 세션 상태에 의존하면 수평 확장과 무중단 교체가 어려워질 수 있음
   - 해결방안: 외부 저장소와 세션 분리를 적용하고 stateless compliance와 rollout success rate로 검증함
2. 문제: 설정을 외부화하지 않으면 환경 차이로 배포 오류가 반복될 수 있음
   - 해결방안: config as code와 secret 관리 체계를 운영하고 config drift count와 deployment rollback rate로 검증함
3. 문제: 원칙만 강조하고 운영 도구가 없으면 개발팀에 규칙 피로만 증가할 수 있음
   - 해결방안: 템플릿과 플랫폼 자동화를 제공하고 onboarding lead time과 platform adoption rate로 검증함

## Ⅶ. 적용 사례

- 클라우드 네이티브 웹앱에서는 12 Factor 원칙을 적용하고, stateless compliance와 rollout success rate로 결과를 확인함
- 플랫폼 팀에서는 설정 관리 표준을 제공하고, config drift count와 deployment rollback rate로 결과를 확인함
- 신규 서비스 템플릿에서는 공통 실행 규칙을 내장하고, onboarding lead time과 platform adoption rate로 결과를 확인함

## Ⅷ. 결론

12 팩터 앱은 체크리스트가 아니라 애플리케이션을 환경에 덜 묶고 배포와 확장에 더 잘 맞추기 위한 운영 설계 원칙임.
