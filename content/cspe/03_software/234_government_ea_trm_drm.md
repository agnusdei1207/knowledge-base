## Ⅰ. 개요
- **정의**: 정부 기관 간 정보시스템의 상호운용성을 확보하기 위한 기술·데이터 참조모델 체계임
- **배경/필요성**: 부처별 독립 구축으로 기술 표준과 데이터 정의가 불일치하여 정보 공유와 연계가 어려우므로, 범정부 차원의 참조모델이 필요함
- **비유**: 각 나라의 전압·플러그를 통일하는 국제 규격처럼, 부처 간 기술·데이터 표준을 맞추는 체계임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공공 EA 참조모델 이해 | TRM 6대 분류, DRM 3대 구성 | EA(232 참조)의 하위 참조모델로 위치를 설명할 것 |

> 요약: TRM은 기술 표준을, DRM은 데이터 표준을 정의하여 부처 간 상호운용성을 확보함

## Ⅱ. 구성요소
```text
범정부 EA --- +--- TRM (기술참조모델) --- 서비스/컴포넌트/표준
              |
              +--- DRM (데이터참조모델) --- 데이터표준/관리/품질
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| TRM 서비스 영역 | 서비스 컴포넌트·기술 표준 프로파일을 6대 영역으로 분류함 | 공구함의 규격별 칸 |
| DRM 데이터 표준 | 범정부 표준 용어·코드·도메인을 정의함 | 사전의 표제어 통일 |
| DRM 데이터 관리 | 데이터 생성·변경·폐기의 생명주기를 관리함 | 문서 관리 대장 |
| DRM 데이터 품질 | 정확성·완전성·일관성 기준으로 데이터 품질을 측정함 | 식품 위생 검사 기준 |

> 요약: TRM의 기술 분류 체계와 DRM의 데이터 표준·관리·품질 체계로 구성됨

## Ⅲ. 절차
```text
표준수립 --> 참조모델 적용 --> 적합성 검증 --> 환류 개선
    v             v               v              v
 TRM/DRM정의   사업적용       EA심의          표준갱신
```
- 1단계: 범정부 TRM/DRM 표준을 수립하고 참조모델을 정의함
- 2단계: 개별 정보화 사업에 TRM/DRM을 적용하여 기술·데이터를 표준화함
- 3단계: EA 적합성 심의를 통해 참조모델 준수 여부를 검증함
- 4단계: 심의 결과와 기술 변화를 반영하여 참조모델을 갱신함

> 요약: 표준 수립 → 사업 적용 → 적합성 검증 → 환류 개선의 순환 구조임

## Ⅳ. 문제점
- 갱신 지연: 기술 변화 속도 대비 참조모델 갱신 주기가 느림 — 최신 기술이 반영되지 않음
- 적용 형식화: 준수 동기 부족 — 심의를 통과하기 위한 형식적 적용에 그침
- 데이터 품질 미흡: 부처별 데이터 관리 역량 차이 — DRM 표준이 실질적으로 이행되지 않음

> 요약: 갱신 지연, 적용 형식화, 데이터 품질 미흡이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 클라우드·AI 등 신기술 영역을 TRM에 분기별 반영하여 갱신 주기를 단축함
2. 중기: EA 적합성 심의 결과를 예산 배정과 연계하여 준수 실효성을 확보함
3. 장기: 부처별 CDO를 지정하고 데이터 품질 관리 체계를 의무화함

> 요약: 신속 갱신, 예산 연계, CDO 체계로 참조모델 실효성을 강화함

## Ⅵ. 전망
- 발전 방향: 디지털플랫폼정부 추진에 따라 API 기반 참조모델로 전환되는 추세임
- 기술사적 판단: 문서 기반 참조모델에서 기계 판독 가능한 메타데이터 중심으로 전환이 필요함
- 기술사 제언: 민간 클라우드 표준과 범정부 TRM을 상호 매핑하여 하이브리드 환경을 지원할 필요
