# 📖 【암기용】 개념 완전 이해

> 목적: 범정부 EA 참조 모형 TRM·DRM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: TRM·DRM은 공공 정보시스템의 기술과 데이터 구조를 공통 기준으로 정리한 참조 모형이다.
- **왜 필요한가**: 기관마다 다른 기술과 데이터 용어를 쓰면 연계, 공동 활용, 유지보수가 어려워진다. 참조 모형은 공공 시스템이 같은 분류와 표준을 보도록 만든다.
- **핵심 직관**: TRM은 공공 IT 기술 분류표, DRM은 공공 데이터 분류표다.

## 깊이 이해
- **배경·문제의식**: 전자정부 시스템은 기관 간 연계와 공동 활용이 많다. 기술 표준과 데이터 분류가 다르면 인터페이스 개발, 데이터 교환, 보안 검토가 반복된다.
- **작동 원리**: EA 수립 시 기술 서비스는 TRM 분류에 맞춰 표준화하고, 데이터 주제영역과 데이터 교환은 DRM 기준에 맞춰 정의한다. 신규 사업은 참조 모형 적합성을 검토해 중복과 표준 이탈을 줄인다.
- **비유**: 여러 도서관이 같은 분류법과 도서 코드 체계를 쓰면 책을 찾고 빌리는 방식이 통일되는 것과 같다.
- **구체 예시**: 기관 A와 B가 주민 민원 데이터를 연계할 때 DRM으로 데이터 주제영역과 항목 의미를 맞추고, TRM으로 API, 인증, DBMS, 운영환경 표준을 확인한다.
- **흔한 오해·주의점**: 참조 모형은 특정 제품 목록이 아니다. 기술·데이터를 분류하고 표준 적용 여부를 판단하는 기준이다.

## 연결 개념
- EA: 참조 모형을 적용해 공공 아키텍처 일관성 확보
- 데이터 표준화: DRM과 연계해 용어·코드·도메인 관리
- 기술 표준: TRM과 연계해 플랫폼·인터페이스·보안 기술 기준 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: TRM·DRM 답안은 공공 EA에서 기술 표준과 데이터 공동 활용을 통제하는 기준이라는 점을 구조와 적용 절차로 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TRM은 기술 서비스 참조 기준, DRM은 데이터 분류·공동 활용 참조 기준이다.
> 2. **가치**: 공공 시스템의 기술 중복, 데이터 의미 불일치, 기관 간 연계 비용을 참조 모형 기반으로 통제한다.
> 3. **판단 포인트**: 제품명 나열보다 EA 심의에서 TRM·DRM 적합성, 표준 준수, 데이터 재사용성을 확인하는 절차가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공공 EA 참조모형 이해 확인 | TRM 기술 참조, DRM 데이터 참조, EA 연계 | TRM과 DRM 역할 혼동 |
| 상호운용성 판단 확인 | 표준 기술, 데이터 주제영역, 공동 활용 | 특정 벤더 기술 목록으로 작성 |
| 적용 절차 이해 확인 | 현행 분류, 목표 표준, 적합성 검토 | 참조 모형을 문서 보관용으로 설명 |

> 요약: 이 문제는 공공 정보화에서 기술과 데이터의 공통 기준을 어떻게 적용해 상호운용성을 확보하는지 묻는다.

## Ⅰ. 개요 및 필요성

TRM·DRM은 범정부 EA의 기술·데이터 참조 기준이다. 공공 시스템은 기관 간 연계와 공동 활용이 많아 표준 기술과 데이터 의미의 일관성이 필요하다. TRM은 기술 분류와 표준을, DRM은 데이터 주제영역과 공유 기준을 제공한다.

---

## Ⅱ. 구조 및 구성요소

```text
공공 정보화 요구 -> EA 원칙 -> TRM 기술 분류
                              +-> DRM 데이터 분류 -> 표준/연계/재사용 검토
```

| 구성요소 | 역할 | 점검 내용 |
|:---|:---|:---|
| TRM | 응용, 데이터, 보안, 운영 기술 서비스 분류 | 표준 기술, 인터페이스, 플랫폼 적합성 |
| DRM | 데이터 주제영역, 항목, 교환 관점 분류 | 데이터 의미, 코드, 공동 활용 가능성 |
| EA Repository | 참조 모형과 기관 아키텍처 산출물 저장 | 현행·목표·전환계획 추적 |
| 적합성 심의 | 신규 사업의 참조모형 준수 확인 | 예외 사유, 대체 표준, 재검토일 |

> 요약: TRM은 기술을, DRM은 데이터를 분류하고 EA 저장소와 심의를 통해 신규 사업 적용 여부를 검증한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사업 요구 식별 -> 업무/데이터/기술 자산 분류 -> TRM/DRM 매핑 -> 표준 적합성 검토 -> 예외 승인/보완 -> 구축 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 신규 사업의 업무, 데이터, 기술 요구 식별 | 요구사항 추적표 |
| 2 | 기술 서비스와 데이터 항목을 참조모형에 매핑 | TRM·DRM 매핑률 |
| 3 | 표준 준수와 중복 여부 검토 | 표준 미준수 건수, 중복 데이터 수 |
| 4 | 예외 승인 또는 보완 계획 확정 | 예외 만료일, 대체 기술 계획 |

> 요약: 참조 모형은 사업 요구를 기술·데이터 분류에 매핑한 뒤 표준 준수와 예외를 관리하는 방식으로 동작한다.

## Ⅳ. 특징

| 구분 | 기관별 자체 기준 | TRM·DRM | 판단 포인트 |
|:---|:---|:---|:---|
| 기술 기준 | 부서별 플랫폼 선택 | 공통 기술 분류와 표준 | 상호운용성, 표준 준수율 |
| 데이터 기준 | 시스템별 명칭·코드 | 주제영역·공통 항목 기준 | 공동 활용, 중복 제거 |
| 한계 | 기준 편차 발생 | 최신 기술 반영 주기 필요 | 예외관리와 갱신 절차 |

> 요약: TRM·DRM은 공공 시스템의 기술·데이터 기준을 맞추지만 최신 기술과 특수 업무는 예외관리로 보완한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | TRM·DRM | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 시스템별 기술·데이터 정의 | 범정부 참조 분류 적용 | 기관 간 연계·공동 활용 필요 시 |
| 비용/성과 | 연계마다 의미 조정 | 표준 매핑 후 재사용 | 인터페이스 수, 중복 데이터 수 |
| 운영/위험 | 표준 이탈 사후 발견 | 착수 전 적합성 검토 | 공공 EA 심의 대상 여부 |

> 요약: TRM·DRM은 연계와 재사용이 많은 공공 시스템에서 사전 표준 검토 기준으로 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 형식적 매핑 | 참조모형 분류만 기입 | 데이터 의미와 기술 표준 근거 첨부 | 매핑 검토 반려율 |
| 표준 노후화 | 클라우드·AI 기술 반영 지연 | 기관 표준 보완표와 예외 만료일 운영 | 표준 갱신 주기 1년 이하 |
| 데이터 불일치 | DRM 매핑 후 코드 표준 미적용 | 공통코드, 메타데이터 관리 | 코드 불일치 건수 |

> 요약: 참조 모형 리스크는 형식적 매핑과 표준 노후화이며 근거 첨부, 갱신 주기, 코드 표준으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| TRM 적합성 | 신규 기술 요소 매핑률 100% | 기술 아키텍처 검토 |
| DRM 적합성 | 핵심 데이터 항목 표준 매핑률 95% 이상 | 데이터 표준 점검 |
| 예외관리 | 예외 승인 건별 대체 계획 100% | 아키텍처 심의 기록 |

> 요약: 적용 성과는 기술·데이터 매핑률과 예외 대체 계획의 완결성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 신규 사업 착수 시 기술 구성요소를 TRM 서비스 분류에 매핑하고 표준 미준수 항목은 예외 사유와 만료일을 기록함
2. 핵심 데이터 항목을 DRM 주제영역, 표준 용어, 공통코드와 연결해 기관 간 교환 항목의 의미 충돌을 제거함
3. EA 심의 체크리스트에 TRM·DRM 매핑률, 표준 미준수 건수, 데이터 재사용 가능 항목 수를 포함함

**결론 (2줄):**
- 기술사 판단: 기관 간 연계와 공동 활용 대상 사업은 TRM·DRM 적합성 검토를 선행하고, 내부 단독 업무는 경량 표준 검토로 적용함
- 향후 방향: 범정부 참조 모형은 클라우드 네이티브, API, AI 데이터 거버넌스 기준을 포함해 지속 갱신되어야 함
