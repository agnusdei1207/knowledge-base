## Ⅰ. 개요
- 정의: OS로부터 자원을 할당받는 작업 단위(Process)와 프로세스 내 실행 흐름 단위(Thread)
- 배경: 멀티태스킹 효율성 증대 및 자원 공유를 통한 응답성 향상 필요
- 출제 의도: 자원 격리(Isolation)와 공유(Sharing)의 메커니즘 차이 이해 여부

## Ⅱ. 구성요소
```
[ Process A ]          [ Process B ]
+-----------+          +-----------+
| Code/Data |          | Code/Data |
|   Heap    |          |   Heap    |
+-----+-----+          +-----+-----+
|Stack|Stack|          |Stack|Stack|
| T1  | T2  |          | T3  | T4  |
+-----+-----+          +-----+-----+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 프로세스 | 실행 중인 프로그램, 독립된 메모리 공간 소유 | 공장 건물 |
| 스레드 | 프로세스 내 실행 경로, Stack 제외 자원 공유 | 공장 내 작업자 |
| TCB | 스레드 제어 블록, CPU 레지스터 및 상태 저장 | 작업 일지 |
> 요약: 프로세스는 독립적 자원 할당 단위, 스레드는 프로세스 내 실행 흐름 단위임.

## Ⅲ. 절차
```
[User App] -> [fork()] -> [Process 생성] -> [pthread_create()] -> [Thread 실행]
```
1. 부모 프로세스가 시스템 호출을 통해 자식 프로세스 생성 (Address Space 복사)
2. 생성된 프로세스 내에서 스레드 생성 요청 (Stack 영역 할당)
3. 스레드 스케줄러에 의해 CPU 제어권 획득 및 명령어 실행
4. 작업 완료 후 스레드 종료 및 프로세스 자원 해제
> 요약: 자원 할당 후 실행 흐름을 분리하여 병렬성 확보함.

## Ⅳ. 문제점
- 원인: 프로세스 간 메모리 격리로 인해 데이터 교환 시 IPC 오버헤드 발생함
- 원인: 멀티스레드 환경에서 공유 자원 접근 시 경합 조건(Race Condition) 발생함

## Ⅴ. 개선방안
- (단기) 뮤텍스/세마포어를 활용한 스레드 간 동기화 기법 적용
- (중기) IPC 성능 개선을 위한 공유 메모리(Shared Memory) 모델 활용
- (장기) 불변 객체(Immutable Object) 및 함수형 프로그래밍 패턴 도입으로 부작용 최소화

## Ⅵ. 전망
- 클라우드 네이티브 환경에서 컨테이너 기반 격리와 고성능 비동기 스레딩 모델(Go-routine 등) 융합 가속화
- 하드웨어 멀티코어 최적화를 위한 런타임 수준의 경량 스레드 스케줄링이 핵심 경쟁력이 될 것임
