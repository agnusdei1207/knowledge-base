## 미리 알고가기

- 프로세스: 운영체제가 주소 공간과 자원을 할당·격리하는 단위임
- 스레드: 프로세스 안에서 스택과 CPU 상태를 따로 가지는 실행 흐름임
- PCB·TCB: 프로세스와 스레드의 실행 상태를 저장하는 커널 자료구조임
- IPC(Inter-Process Communication): 주소 공간이 분리된 프로세스 사이에서 파이프·메시지 큐·공유 메모리로 데이터를 주고받는 통신 방식임

## 작성 근거(검토용)

- 프로세스와 스레드는 자원 공유·통신 방식, 전환 범위, 장애 영향이라는 3개 판단축으로 구분함
- 생성 API를 임의 순서로 연결한 절차는 삭제하고 정적 구조와 선택 조건에 집중함
- 서버 사례는 격리와 공유가 실제로 드러나는 프로세스·스레드 풀로 연결함

## Ⅰ. 개요
- **정의/개념**: 프로세스는 주소 공간과 자원을 할당받는 단위이고, 스레드는 프로세스의 자원을 공유하며 명령을 실행하는 흐름임
- **배경/필요성**: 실행 환경의 격리 범위와 자원 공유 범위를 정하기 위해 프로세스와 스레드의 구분이 필요함

## Ⅱ. 특징

- 프로세스는 독립 주소 공간을 사용해 다른 프로세스의 메모리 접근을 제한함
- 같은 프로세스의 스레드는 코드·데이터·힙·열린 파일을 공유함
- 스레드는 스택·프로그램 카운터·레지스터 상태를 따로 유지함
- 프로세스 전환은 주소 공간을, 스레드 전환은 실행 상태를 교체함

## Ⅲ. 종류 및 비교

| 판단 기준 | 프로세스 | 스레드 |
|:---|:---|:---|
| 자원 공유·통신 | 독립 주소 공간, IPC 통신 | 주소 공간·힙 공유, 동기화 통신 |
| 전환 범위 | 주소 공간과 실행 상태 교체 | 실행 상태만 교체 |
| 장애 영향 | 다른 프로세스와 격리 | 같은 프로세스의 스레드에 전파 가능 |

> 요약: 프로세스는 주소 공간을 분리하고, 스레드는 프로세스 자원을 공유하며 실행 상태만 따로 유지함.

## Ⅳ. 구성요소 및 구조
```
[ Process A ]          [ Process B ]
+-----------+          +-----------+
| Code/Data |          | Code/Data |
|   Heap    |          |   Heap    |
+-----+-----+          +-----+-----+
|Stack|Stack|          |Stack|Stack|
| T1  | T2  |          | T3  | T4  |
+-----+-----+          +-----+-----+
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 프로세스 | 독립 주소 공간과 파일·보안 정보를 가지는 자원 할당 단위임 | 격리 범위 |
| 스레드 | 프로세스 자원을 공유하고 스택·레지스터 상태를 따로 가짐 | 실행 흐름 수 |
| PCB | 프로세스 상태·메모리·열린 파일 정보를 저장함 | 프로세스 복원 |
| TCB | 스레드의 프로그램 카운터·레지스터·스택 정보를 저장함 | 스레드 복원 |
> 요약: 프로세스는 독립적 자원 할당 단위, 스레드는 프로세스 내 실행 흐름 단위임.

## Ⅵ. 실무 사례

1. 플러그인 실행 서버는 작업별 프로세스를 분리하고 비정상 종료의 전파 범위와 IPC 지연을 확인함
2. API 서버는 스레드 풀로 요청을 병렬 처리하고 작업 큐 대기시간과 스레드 경합률을 확인함

## Ⅶ. 결론

- 프로세스와 스레드는 주소 공간 격리 요구와 공유 데이터 접근 빈도를 기준으로 선택함
