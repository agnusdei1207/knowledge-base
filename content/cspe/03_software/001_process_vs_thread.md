## Ⅰ. 개요
- 정의: 프로세스는 운영체제가 주소 공간과 자원을 할당하는 단위이며, 스레드는 프로세스 안에서 명령을 실행하는 흐름 단위임
- 배경: 독립 실행과 자원 공유 요구가 함께 존재하므로 실행 단위 구분이 필요함
- 출제 의도: 자원 격리(Isolation)와 공유(Sharing)의 메커니즘 차이 이해 여부

## Ⅱ. 구성요소
```
[ Process A ]          [ Process B ]
+-----------+          +-----------+
| Code/Data |          | Code/Data |
|   Heap    |          |   Heap    |
+-----+-----+          +-----+-----+
|Stack|Stack|          |Stack|Stack|
| T1  | T2  |          | T3  | T4  |
+-----+-----+          +-----+-----+
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 프로세스 | 실행 중인 프로그램, 독립된 메모리 공간 소유 | 격리와 보호 |
| 스레드 | 프로세스 내 실행 경로, Stack 제외 자원 공유 | 공유와 응답성 |
| TCB | 스레드 제어 블록, CPU 레지스터 및 상태 저장 | 실행 흐름 복원 |
> 요약: 프로세스는 독립적 자원 할당 단위, 스레드는 프로세스 내 실행 흐름 단위임.

## Ⅲ. 절차
```
[User App] -> [fork()] -> [Process 생성] -> [pthread_create()] -> [Thread 실행]
```
1. 부모 프로세스가 시스템 호출로 자식 프로세스를 생성하고 독립 주소 공간을 구성함
2. 생성된 프로세스 내에서 스레드 생성 요청 (Stack 영역 할당)
3. 스레드 스케줄러에 의해 CPU 제어권 획득 및 명령어 실행
4. 작업 완료 후 스레드 종료 및 프로세스 자원 해제
> 요약: 자원 경계와 실행 흐름을 분리해 동시 실행 단위를 정함.

## Ⅳ. 문제점
- 원인: 프로세스 간 메모리 격리로 인해 데이터 교환 시 IPC 오버헤드 발생함
- 원인: 멀티스레드 환경에서 공유 자원 접근 시 경합 조건(Race Condition) 발생함

## Ⅴ. 개선방안
- (단기) 뮤텍스/세마포어를 활용한 스레드 간 동기화 기법 적용
- (중기) IPC 성능 개선을 위한 공유 메모리(Shared Memory) 모델 활용
- (장기) 불변 객체(Immutable Object) 및 함수형 프로그래밍 패턴 도입으로 부작용 최소화

## Ⅵ. 전망
- 클라우드 네이티브 환경에서는 컨테이너 격리와 언어 런타임의 경량 실행 단위가 함께 쓰임
- 멀티코어 서버에서는 커널 스레드와 사용자 수준 스케줄링의 역할 분리가 설계 쟁점이 됨

## 작성 근거(검토용)

- 프로세스와 스레드는 속도 비교보다 자원 격리, 공유 범위, 실행 흐름 복원 기준으로 구분해야 하므로 표의 예시열을 판단 기준으로 교체함
- 전망은 추상적 경쟁력 대신 컨테이너 격리와 런타임 스케줄링처럼 실제 설계 쟁점이 되는 단어로 제한함
