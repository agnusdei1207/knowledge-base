## Ⅰ. 개요
- **정의**: 프로세스는 독립 메모리를 가진 실행 단위, 스레드는 프로세스 내 자원을 공유하는 경량 실행 단위임
- **배경/필요성**: 단일 프로세스 모델은 병렬 작업 시 메모리 복제 비용이 과다하여 자원 공유 기반 경량 실행 단위가 필요함
- **비유**: 프로세스는 독립된 사무실, 스레드는 같은 사무실 내 각자 책상에서 일하는 직원임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 자원 격리와 공유의 트레이드오프 이해 | 메모리 구조 차이(코드/데이터/힙 공유 여부) | 스레드 간 동기화 문제를 누락하지 말 것 |

> 요약: 프로세스는 격리성, 스레드는 공유 효율성을 제공하며 용도에 따라 선택함

## Ⅱ. 구성요소
```text
[Process A]                    [Process B]
+--------+--------+           +--------+--------+
| Code   | Data   |           | Code   | Data   |
+--------+--------+           +--------+--------+
| Heap   | Stack  |           | Heap   | Stack  |
+--------+--------+           +--------+--------+

[Process with Threads]
+---------------------------+
| Code | Data | Heap (공유) |
+------+------+------+------+
| Stack1 | Stack2 | Stack3  |  <-- 스레드별 독립
+--------+--------+---------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 프로세스 메모리 | 코드/데이터/힙/스택 전부 독립 할당됨 | 각자 냉장고가 있는 원룸 |
| 스레드 스택 | 스레드마다 고유 스택을 보유하여 함수 호출 독립 수행함 | 개인 서랍장 |
| 공유 영역 | 코드/데이터/힙을 스레드 간 공유하여 메모리 절약함 | 공용 회의실 |

> 요약: 프로세스는 전 영역 독립, 스레드는 스택만 독립이고 나머지는 공유함

## Ⅲ. 절차
```text
fork() --> 메모리 복제 --> 독립 프로세스 생성
pthread_create() --> 스택 할당 --> 공유 공간 내 스레드 생성
```
- 1단계: OS가 `fork()` 또는 `pthread_create()` 시스템 호출을 수신함
- 2단계: 프로세스는 PCB 생성 및 전체 메모리 복제, 스레드는 TCB 생성 및 스택만 할당함
- 3단계: 스케줄러가 Ready Queue에 등록하여 CPU 할당을 대기함
- 4단계: 컨텍스트 스위칭 시 프로세스는 전체 교체, 스레드는 스택/레지스터만 교체함

> 요약: 생성·전환 비용에서 스레드가 프로세스보다 경량임

## Ⅳ. 문제점
- 스레드 동기화 오류: 공유 자원 접근 시 Race Condition 발생 — 데이터 정합성이 깨짐
- 프로세스 생성 비용: `fork()` 시 전체 메모리를 복제 — 대량 생성 시 메모리·시간 낭비됨
- 스레드 장애 전파: 한 스레드의 비정상 종료가 전체 프로세스를 종료시킴 — 격리 불가함

> 요약: 스레드는 공유로 인한 동기화·장애 전파, 프로세스는 복제 비용이 문제임

## Ⅴ. 개선방안
1. 단기: Mutex/Semaphore 등 동기화 기법을 적용하여 Race Condition을 방지함
2. 중기: Copy-on-Write 기법으로 `fork()` 시 실제 쓰기 시점까지 복제를 지연함
3. 장기: 컨테이너·마이크로VM 등 경량 격리 기술로 스레드 수준 효율과 프로세스 수준 격리를 동시 확보함

> 요약: 동기화·CoW·경량 격리로 각 단점을 보완함

## Ⅵ. 전망
- 발전 방향: 코루틴, 가상 스레드(Java Virtual Thread) 등 유저 레벨 경량 실행 단위가 확산됨
- 기술사적 판단: 멀티코어 확대로 스레드 활용이 기본이나 격리 요구도 병행하여 하이브리드 모델이 주류임
- 기술사 제언: 워크로드 특성(I/O 바운드 vs CPU 바운드)에 따라 프로세스·스레드·코루틴을 적절히 선택할 필요
