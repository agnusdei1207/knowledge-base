## 미리 알고가기

- 뮤테이션 테스트는 코드에 작은 변형을 넣고 테스트가 이를 잡아내는지 보는 방식임
- surviving mutant가 많으면 테스트의 결함 탐지력이 약하다는 신호임
- 커버리지보다 테스트 품질을 더 직접적으로 본다

## Ⅰ. 개요

- **정의/개념**: 뮤테이션 테스트는 연산자 변경이나 조건 반전 같은 작은 코드 변형을 인위적으로 만들어 기존 테스트가 이를 실패로 탐지하는지 측정함으로써 테스트 스위트의 실질적 결함 탐지력을 평가하는 기법임
- **배경/필요성**: 높은 커버리지만으로는 테스트 품질을 알기 어려우므로, 테스트가 실제 오류를 얼마나 잘 잡는지 더 직접적으로 검증할 기준이 필요함

## Ⅱ. 특징

- 테스트가 단순 실행만 했는지 의미 있는 검증까지 했는지 드러냄
- surviving mutant는 assertion 부족이나 시나리오 약점을 보여줌
- 실행 비용이 커서 전체 코드베이스에 상시 적용하기는 부담이 있음
- 등가 mutant 판별이 어려워 해석 난도가 있다

## Ⅲ. 종류 및 비교

| 판단 기준 | 커버리지 측정 | 뮤테이션 테스트 |
|:---|:---|:---|
| 관점 | 무엇을 실행했는가 | 오류를 잡아낼 수 있는가 |
| 장점 | 빠르고 범용적 | 테스트 강도 평가에 직접적 |
| 한계 | 품질 보장 약함 | 비용과 해석 난도 큼 |
| 적합 환경 | 기본 품질 지표 | 핵심 모듈 테스트 품질 평가 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Mutation Operator | 조건 반전과 상수 변경 같은 작은 변형 규칙이 오류 후보를 만듦 |
| Mutant Set | 생성된 변형 코드 집합이 테스트 강도 평가 대상이 됨 |
| Test Execution Result | mutant가 죽는지 살아남는지에 따라 테스트 품질을 판단함 |
| Equivalent Mutant Handling | 실제로는 의미 차이가 없는 변형을 걸러내야 지표 왜곡을 줄일 수 있음 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| mutant 생성    | --> | 테스트 실행    | --> | 생존 mutant 분석 | --> | 테스트 보강    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **mutant 생성**: 코드에 작은 결함 후보를 주입함
2. **테스트 실행**: 기존 테스트 스위트를 돌림
3. **생존 mutant 분석**: 잡히지 않은 변형의 원인을 분석함
4. **테스트 보강**: assertion이나 시나리오를 추가함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 전체 시스템에 무차별 적용하면 실행 시간이 길어져 파이프라인 병목이 될 수 있음
   - 해결방안: 핵심 모듈과 야간 배치에 한정하고 mutation runtime cost와 pipeline impact score로 검증함
2. 문제: equivalent mutant가 많으면 살아남은 mutant 수치가 실제보다 나쁘게 보일 수 있음
   - 해결방안: 필터 규칙과 수동 검토를 병행하고 equivalent mutant ratio와 analysis precision으로 검증함
3. 문제: surviving mutant를 수정하지 않고 수치만 보고하면 테스트 개선으로 이어지지 않을 수 있음
   - 해결방안: 보강 작업과 연계하고 survivor remediation rate와 assertion quality score로 검증함

## Ⅶ. 적용 사례

- 핵심 계산 엔진에서는 뮤테이션 테스트를 적용하고, mutation score와 survivor remediation rate로 결과를 확인함
- 야간 품질 배치에서는 비용을 통제하며 수행하고, mutation runtime cost와 pipeline impact score로 결과를 확인함
- 테스트 품질 개선 활동에서는 surviving mutant를 분석하고, equivalent mutant ratio와 assertion quality score로 결과를 확인함

## Ⅷ. 결론

뮤테이션 테스트의 가치는 커버리지 숫자를 보완해 테스트가 실제 오류를 잡아낼 힘이 있는지 보여주는 데 있음.
