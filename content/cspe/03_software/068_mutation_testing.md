## 미리 알고가기

- 뮤테이션 테스트는 코드에 작은 변형을 넣고 기존 테스트가 그 변형을 잡아내는지 확인하는 방식임
- 생존 변이는 변형된 코드가 테스트에서 걸리지 않고 살아남은 경우를 뜻함
- 등가 변이는 코드를 바꿨지만 실제 동작 의미는 달라지지 않는 변형을 뜻함

## 작성 근거(검토용)

- 뮤테이션 테스트는 확인 관점, 측정 결과, 실행 부담, 적용 환경을 핵심 비교축으로 선정함
- 구성과 절차는 변이 생성부터 사멸·생존 판정과 테스트 보강까지의 흐름을 중심으로 제시함
- 실무 판단은 변이 점수, 추가 실행시간, 생존 변이 해소율로 구체화함

## Ⅰ. 개요

- **정의/개념**: 뮤테이션 테스트는 코드에 작은 변이를 만들고 기존 테스트가 이를 실패로 탐지하는지 측정하는 테스트 판별력 평가 기법임
- **배경/필요성**: 높은 커버리지가 실제 오류 탐지를 보장하지 않으므로 테스트가 결함을 판별하는 능력을 직접 측정할 기준이 필요함

## Ⅱ. 특징

- 연산자·조건·반환값을 변형한 코드에서 테스트가 실패하는지 측정함
- 생존 변이는 결과 검증 조건이나 오류 시나리오가 부족함을 보여줌
- 생성한 변이 수만큼 테스트를 반복해 실행시간과 자원 사용량이 늘어남
- 등가 변이 판별이 어려워 결과 해석에 주의가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 커버리지 측정 | 뮤테이션 테스트 |
|:---|:---|:---|
| 확인 관점 | 어떤 코드가 실행됐는지를 봄 | 테스트가 실제 오류를 잡는지를 봄 |
| 측정 결과 | 실행된 문장·분기·조건 비율 | 생성한 변이 중 테스트가 탐지한 비율 |
| 구조상 한계 | 코드 실행만으로 결함 탐지력을 보장하지 못함 | 변이 수에 따라 실행시간이 늘고 등가 변이 판별이 필요함 |
| 대표 환경 | 일상적인 테스트 실행 범위 모니터링 | 결함 비용이 큰 규칙·계산 모듈의 테스트 판별력 평가 |

> 요약: 커버리지는 코드 실행 범위, 뮤테이션 테스트는 주입한 오류를 탐지하는 테스트 판별력을 측정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변이 규칙 | 조건 반전과 상수 변경 같은 변형 규칙이 오류 후보를 만듦 |
| 변이 집합 | 생성된 변형 코드 집합이 테스트 강도 평가 대상이 됨 |
| 테스트 실행 결과 | 변이의 사멸·생존 여부에 따라 테스트 판별력을 평가함 |
| 등가 변이 처리 | 의미가 변하지 않는 변이를 걸러내야 지표 왜곡을 줄일 수 있음 |

> 요약: 변이 규칙으로 오류 후보를 만들고 테스트 결과로 사멸·생존을 판정한 뒤 등가 변이를 제외함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변이 생성      | --> | 테스트 실행    | --> | 생존 변이 분석 | --> | 테스트 보강    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변이 생성**: 코드에 작은 결함 후보를 주입함
2. **테스트 실행**: 기존 테스트 스위트를 수행함
3. **생존 변이 분석**: 잡히지 않은 변형의 원인을 분석함
4. **테스트 보강**: 결과 검증 조건이나 오류 시나리오를 추가함

> 요약: 코드 변이를 실행한 테스트가 실패하면 사멸, 통과하면 생존으로 판정하고 생존 원인을 보강함.

## Ⅵ. 실무 사례

1. 계산 엔진은 야간에 뮤테이션 테스트를 실행하고 변이 점수·추가 실행시간을 확인함
2. 생존 변이는 등가 여부를 검토하고 테스트를 보강해 생존 변이 해소율을 확인함

## Ⅶ. 결론

뮤테이션 테스트는 코드 변이를 기존 테스트가 탐지하는지 측정해 테스트 묶음의 실제 결함 판별력을 평가함
