## 미리 알고가기

- 뮤테이션 테스트는 코드에 작은 변형을 넣고 기존 테스트가 그 변형을 잡아내는지 확인하는 방식임
- 생존 변이는 변형된 코드가 테스트에서 걸리지 않고 살아남은 경우를 뜻함
- 등가 변이는 코드를 바꿨지만 실제 동작 의미는 달라지지 않는 변형을 뜻함

## Ⅰ. 개요

- **정의/개념**: 뮤테이션 테스트는 연산자 변경이나 조건 반전 같은 작은 코드 변형을 인위적으로 만들고 기존 테스트가 이를 실패로 탐지하는지 측정해 테스트 스위트의 실제 결함 탐지력을 평가하는 기법임.
- **배경/필요성**: 커버리지가 높아도 테스트가 의미 있는 검증을 하는지는 별개이므로, 테스트가 실제 오류를 얼마나 잘 잡는지 더 직접적으로 확인할 기준이 필요함.

## Ⅱ. 특징

- 테스트가 단순 실행만 했는지 실제 오류를 잡을 힘이 있는지 드러냄
- 생존 변이는 검증 문장 부족이나 시나리오 약점을 보여줌
- 실행 비용이 커서 전체 코드에 상시 적용하기는 부담이 큼
- 등가 변이 판별이 어려워 결과 해석에 주의가 필요함

## Ⅲ. 종류 및 비교

| 구분 | 커버리지 측정 | 뮤테이션 테스트 |
|:---|:---|:---|
| 확인 관점 | 어떤 코드가 실행됐는지를 봄 | 테스트가 실제 오류를 잡는지를 봄 |
| 구조상 장점 | 빠르고 범용적으로 적용하기 쉬움 | 테스트 강도를 직접적으로 평가하기 좋음 |
| 구조상 한계 | 실행만 했다고 해서 좋은 테스트라고 말할 수 없음 | 시간과 자원이 많이 들고 해석 난도가 높음 |
| 적합한 환경 | 기본 품질 지표와 일상 모니터링에 맞음 | 핵심 모듈의 테스트 품질 평가에 맞음 |

> 요약: 뮤테이션 테스트는 커버리지 숫자를 보완해 테스트가 실제 오류를 잡을 수 있는지 보여주는 기법임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변이 규칙 | 조건 반전과 상수 변경 같은 변형 규칙이 오류 후보를 만듦 |
| 변이 집합 | 생성된 변형 코드 집합이 테스트 강도 평가 대상이 됨 |
| 테스트 실행 결과 | 변이가 죽었는지 살아남았는지에 따라 테스트 품질을 판단함 |
| 등가 변이 처리 | 의미가 변하지 않는 변이를 걸러내야 지표 왜곡을 줄일 수 있음 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변이 생성      | --> | 테스트 실행    | --> | 생존 변이 분석 | --> | 테스트 보강    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변이 생성**: 코드에 작은 결함 후보를 주입함
2. **테스트 실행**: 기존 테스트 스위트를 수행함
3. **생존 변이 분석**: 잡히지 않은 변형의 원인을 분석함
4. **테스트 보강**: 검증 문장이나 시나리오를 추가함

## Ⅵ. 실무 적용 및 유의점

1. 핵심 계산 엔진과 규칙 검증 모듈에서는 뮤테이션 테스트가 유용하지만 전체 파이프라인에 무차별 적용하면 병목이 되므로 중요 모듈과 야간 배치에 한정하고 변이 점수와 추가 실행 시간으로 확인함
2. 생존 변이를 수치로만 보고 끝내면 테스트 품질 개선으로 이어지지 않으므로 등가 변이 검토와 보강 작업을 함께 운영하고 생존 변이 해소율과 검증 문장 보강 비율로 확인함

## Ⅶ. 결론

뮤테이션 테스트는 테스트가 코드를 실행했는지보다 실제 오류를 잡을 힘이 있는지 확인할 때 가치가 큼.
