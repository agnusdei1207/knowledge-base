## Ⅰ. 개요
- **정의**: 데이터의 원천부터 최종 소비까지 흐름과 변환 이력을 추적하는 체계
- **배경/필요성**: 데이터 오류 발생 시 원인 역추적이 어려워 영향 범위 파악과 신속 대응이 필요함
- **비유**: 식품의 원산지 이력 추적 시스템과 같음 — 문제 발생 시 원인 식재료까지 역추적 가능

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 거버넌스 추적 능력 | 컬럼 수준 리니지, 영향도 분석 | 리니지와 데이터 카탈로그(153 참조) 역할 구분 |

> 요약: 데이터의 생성-변환-소비 경로를 시각화하여 추적성을 확보하는 체계임

## Ⅱ. 구성요소
```text
[원천 시스템] --> [ETL/변환] --> [저장소] --> [리포트/분석]
      |               |             |              |
      +---------- [리니지 메타데이터 수집기] -------+
                          |
                   [리니지 그래프 DB]
                          |
                   [시각화/영향도 분석]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 리니지 수집기 | ETL·쿼리 로그에서 변환 관계를 자동 파싱하는 모듈 | CCTV 녹화기 |
| 리니지 그래프 DB | 테이블·컬럼 간 변환 관계를 방향 그래프로 저장 | 가계도 |
| 영향도 분석 | 특정 컬럼 변경 시 하위 영향 범위를 산출하는 기능 | 도미노 시뮬레이션 |
| 시각화 | 리니지 경로를 DAG 형태로 표현하는 UI | 지하철 노선도 |

> 요약: 변환 관계를 그래프로 저장하고 영향도 분석·시각화를 제공하는 구조임

## Ⅲ. 절차
```text
메타데이터 수집 --> 관계 파싱 --> 그래프 구축 --> 영향도 분석
```
- 1단계: 메타데이터 수집 — ETL 로그·SQL 파싱·API 호출 이력을 추출함
- 2단계: 관계 파싱 — 입력-출력 컬럼 간 변환 매핑을 식별함
- 3단계: 그래프 구축 — 파싱 결과를 방향 그래프(DAG)로 저장함
- 4단계: 영향도 분석 — 변경 대상 컬럼의 상류·하류 영향 범위를 산출함

> 요약: 수집-파싱-그래프구축-분석의 4단계로 데이터 추적성을 확보함

## Ⅳ. 문제점
- 수집 범위 한계: 비정형·수동 변환은 자동 파싱 불가 — 리니지 단절 발생
- 그래프 복잡도: 대규모 파이프라인에서 노드·엣지 폭증 — 탐색 성능 저하
- 실시간 갱신 부재: 배치 수집 시 변경 반영 지연 — 최신 리니지 미보장

> 요약: 수집 한계, 그래프 복잡도, 갱신 지연이 주요 장애 요인임

## Ⅴ. 개선방안
1. 단기: 수동 변환에 대한 어노테이션 API 제공으로 리니지 단절 해소
2. 중기: 그래프 압축·레이어링 기법 적용으로 탐색 성능 개선
3. 장기: 스트림 기반 실시간 리니지 수집 아키텍처 도입

> 요약: 수집 보완, 그래프 최적화, 실시간 전환으로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: 컬럼 수준 리니지에서 값 수준(row-level) 리니지로 정밀화 진행
- 기술사적 판단: 데이터 카탈로그(153 참조)·품질(152 참조)과 통합된 옵저버빌리티 플랫폼 확산
- 기술사 제언: 규제 준수(GDPR 등) 요건에 리니지를 연계하여 감사 추적 체계를 확보할 필요
