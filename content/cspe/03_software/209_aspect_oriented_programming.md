## Ⅰ. 개요
- 핵심 비즈니스 로직과 공통 관심사(횡단 관심사)를 분리하여 모듈화하는 기법임
- 여러 모듈에 반복되는 공통 로직을 한 곳에서 변경하도록 OOP의 모듈화 범위를 보완함
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 횡단 관심사(Cross-cutting), Join point, Advice, Weaving | 햄버거의 패티(핵심)와 포장지/영수증(공통) |

## Ⅱ. 구성요소
- 핵심 로직(Core Concern)과 이를 가로지르는 횡단 로직(Aspect)임
[로그] ---+--- [로직 A] ---+--- [보안]
[트랜잭션] +--- [로직 B] ---+--- [캐시]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Aspect | 횡단 관심사(보안, 로그 등)를 모듈화한 단위 | 공통 관리 지침서 |
| Join Point | Advice가 적용될 수 있는 실행 시점 (메소드 호출 등) | 공정 중의 체크포인트 |
| Advice | 특정 Join Point에서 실행되는 실제 코드 (Action) | 체크포인트에서의 작업 내용 |
> 요약: 비즈니스 코드에 로깅/트랜잭션 코드를 직접 쓰지 않고 외부에서 주입함

## Ⅲ. 절차
- 관심사 분리 및 런타임/컴파일 시점 결합 절차임
[공통 기능 정의] -> [Pointcut 설정] -> [Advice 작성] -> [Weaving]
- 4단계 설명
1) Aspect 식별: 여러 모듈에 흩어져 있는 공통 로직(로깅 등)을 추출함
2) Pointcut 정의: Advice를 적용할 타겟 메소드 선별 규칙을 작성함
3) Advice 구현: 실행 전(Before), 후(After), 예외 시 등의 로직을 코딩함
4) 위빙(Weaving): Aspect를 실제 코드에 결합함 (컴파일/클래스로딩/런타임 방식)
> 요약: Pointcut으로 적용 대상을 선택하고 Advice를 위빙하여 공통 로직과 업무 로직을 분리함

## Ⅳ. 문제점
- 프로그램 실행 흐름이 암시적으로 변경되어 디버깅 및 가독성이 저하될 수 있음 (원인: 추상화)
- 프록시 기반 런타임 위빙은 메서드 호출을 가로채는 과정에서 추가 호출 비용이 발생함

## Ⅴ. 개선방안
- (단기) 명확한 명명 규칙을 적용하여 Pointcut 대상을 쉽게 식별 가능케 함
- (중기) 컴파일 시점 위빙(AspectJ 등)을 활용하여 런타임 성능 저하 방지함
- (장기) 아키텍처 설계 단계부터 횡단 관심사를 정의하는 관점 지향 설계(AOD) 도입함

## Ⅵ. 전망
- 클라우드 네이티브의 관측성(Observability) 확보를 위한 분산 트레이싱에 핵심적으로 활용됨
- AI가 코드 패턴을 분석하여 중복된 횡단 관심사를 자동 Aspect로 추출하는 기술이 부상할 것임
