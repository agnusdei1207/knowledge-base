## Ⅰ. 개요
- 정의: 대표 사용자가 목표 과업을 수행할 때 성공률·소요 시간·오류·만족도를 측정하는 활동
- 배경: 기능적 완성도만큼 사용자 인터페이스(UI)와 사용자 경험(UX)의 중요성 증대
- 출제 의도: 사용성 평가 지표(학습성, 효율성 등) 및 평가 기법(Heuristic 등) 이해

## Ⅱ. 구성요소
- 구조도
  [Usability Metrics]
  |-- [Learnability] : 처음 쓸 때 쉬운가?
  |-- [Efficiency]   : 빨리 목표 달성 가능한가?
  |-- [Satisfaction] : 만족스러운가?

- 구성요소 표
| 평가 기법 | 설명 | 특징 |
| :--- | :--- | :--- |
| 휴리스틱 평가 | 전문가가 10대 사용성 원칙에 비추어 진단 | 전문가 주관, 신속 |
| 인터뷰/관찰 | 실제 사용자가 태스크 수행하는 과정 기록 | Think Aloud 기법 활용 |
| 설문 조사 | 시스템 사용 후 만족도 정량 측정 | SUS(System Usability Scale) |
> 요약: 휴리스틱·관찰·설문으로 과업 성공률, 수행 시간, 오류 지점과 만족도를 수집함

## Ⅲ. 절차
- 흐름도
  대상 사용자 정의 -> 테스트 시나리오 설계 -> 평가 수행 -> 개선안 도출
- 4단계 설명
1. 대상 사용자 정의: 실제 제품을 사용할 타겟 고객군(Persona) 선정 및 섭외
2. 시나리오 설계: 시스템의 핵심 기능을 포함한 일상적인 태스크(Task) 목록 작성
3. 평가 수행: 사용자가 태스크를 수행하는 동안 발화 및 행동을 녹화/관찰
4. 개선안 도출: 실패 지점 및 불편 사항(Pain Points)을 분석하여 UI/UX 수정 가이드 작성
> 요약: 대표 사용자의 과업 수행을 관찰하고 실패 지점과 발화 내용을 UI 개선 항목에 연결함

## Ⅳ. 문제점
- 소수의 테스트 참여자 결과만으로 전체 사용자의 성향을 일반화하는 오류 리스크
- 기능 구현 일정에 쫓겨 사용성 개선안이 실제 개발 우선순위에서 밀리는 현상

## Ⅴ. 개선방안
- 정성적 인터뷰와 정량적 로그 데이터(A/B Test)의 상호 보완적 분석 실시
- 프로토타이핑 단계부터 반복적(Iterative) 평가를 수행하여 수정 비용 절감

## Ⅵ. 전망
- 아이트래킹, 뇌파 분석 등 생체 신호를 활용한 정밀 사용성 측정 기술 도입
- CSF: 단순히 '보기 좋은' 디자인이 아닌 '쓰기 편한' 기능적 유용성 확보 주력
