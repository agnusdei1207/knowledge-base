## Ⅰ. 개요
- **정의**: 유한 상태 모델의 전체 상태 공간을 자동 탐색하여 속성 만족 여부를 검증하는 기법
- **배경/필요성**: 정리 증명의 수동 부담 없이 자동으로 반례를 생성할 수 있는 검증 수단이 필요함
- **비유**: 미로의 모든 경로를 전수 탐색하여 출구 도달 가능 여부를 확인하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정형 검증(287) 하위 기법 구분 | 상태 전이 시스템·시제 논리 | 상태 폭발(State Explosion) 대응 기법 포함 필요 |

> 요약: 유한 상태 공간 전수 탐색으로 속성 위반을 자동 검출하는 정형 검증 기법임

## Ⅱ. 구성요소
```text
System Model + Property Spec --> Model Checker --> Satisfied / Counterexample
      |              |                |
  Kripke Struct   LTL/CTL        BDD/SAT Engine
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 크립키 구조 | 상태·전이·레이블로 시스템 동작을 표현하는 유한 모델 | 미로 지도 |
| 시제 논리 | LTL·CTL로 "항상", "결국" 등 시간 기반 속성 명세 | 규칙 조건표 |
| BDD/SAT 엔진 | 이진 결정 다이어그램·SAT 솔버로 상태 공간 압축 탐색 | 지도 축약 탐색 알고리즘 |
| 반례(Counterexample) | 속성 위반 시 위반 경로를 구체적 실행 순서로 출력 | 오류 재현 시나리오 |

> 요약: 크립키 구조+시제 논리를 BDD/SAT 엔진으로 자동 검증하는 체계임

## Ⅲ. 절차
```text
모델 명세 --> 속성 정의 --> 상태 탐색 --> 결과 분석
```
- 1단계: 시스템을 크립키 구조·전이 시스템으로 모델링
- 2단계: 검증 대상 속성을 LTL·CTL 등 시제 논리 공식으로 정의
- 3단계: 모델 체커가 BDD·SAT 기반으로 전체 상태 공간 자동 탐색
- 4단계: 속성 만족 시 증명 완료, 위반 시 반례 경로 분석 후 모델 수정

> 요약: 모델링→속성 정의→자동 탐색→반례 분석으로 시스템 속성을 검증함

## Ⅳ. 문제점
- 상태 폭발: 병렬 프로세스·변수 증가 시 상태 수 지수 증가 — 메모리·시간 한계 초과
- 모델 구축 부담: 실제 시스템을 정확히 반영하는 추상 모델 작성에 전문성 필요
- 무한 상태 미지원: 정수·실수 등 무한 도메인 변수 포함 시 직접 적용 불가

> 요약: 상태 폭발·모델 구축 부담·무한 상태 미지원이 주요 한계임

## Ⅴ. 개선방안
1. 단기: 대칭 축소·편순서 축소(Partial Order Reduction)로 탐색 상태 수 감축
2. 중기: CEGAR(반례 기반 추상화 세분화) 기법으로 자동 추상화 수준 조절
3. 장기: 유계 모델 체킹(BMC)·SMT 솔버 결합으로 무한 상태 근사 검증 지원

> 요약: 상태 축소·자동 추상화·BMC로 모델 체킹 적용 범위 확대 필요

## Ⅵ. 전망
- 발전 방향: 소프트웨어 모델 체킹(SPIN, CBMC 등)으로 코드 수준 직접 검증 확산
- 기술사적 판단: 안전 필수 시스템(286) 인증에서 모델 체킹 활용 의무화 추세임
- 기술사 제언: 모델 체킹과 테스트·정적 분석의 상호 보완 V&V 전략 수립 필요
