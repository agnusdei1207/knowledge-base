## 미리 알고가기

- 읽기 이상 현상(Read Anomalies): 동시 실행 트랜잭션들 사이의 격리 장치 부재로 조회 결과에 일관성이 깨지는 현상임
- Dirty Read: 아직 커밋(Commit)되지 않은 다른 트랜잭션의 변경 데이터를 읽는 오류임
- Non-Repeatable Read: 동일 트랜잭션 내에서 같은 데이터를 재조회했을 때 그 사이에 커밋된 갱신값으로 인해 조회결과가 달라지는 오류임
- Phantom Read: 동일 트랜잭션 내에서 동일 범위 조건을 재조회했을 때 그 사이에 커밋된 삽입/삭제 행들로 인해 결과 집합이 달라지는 오류임
- 공유 잠금(Shared Lock): 데이터를 조회할 때 설정하여 다른 사용자의 쓰기만을 제한하는 잠금임
- 배타 잠금(Exclusive Lock): 데이터를 갱신할 때 설정하여 다른 사용자의 읽기와 쓰기를 모두 제한하는 잠금임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 동시성 제어 실패 시 발생하는 대표적 3대 읽기 이상 현상(Dirty Read, Non-Repeatable Read, Phantom Read)의 동작 원리와 방지 방안을 비교 검증하기 위함
- 절 구성 및 전개 흐름 이유: 개요에서 이상 현상의 정의를 제시하고, 특징을 요약함. 비교표를 통해 세 유형의 발생 원인과 해결 수단을 명확히 대조하고, 구조에서는 원인이 되는 데이터 공유 관계를 가시화함. 절차에서는 시간에 따른 읽기 이상 발생 시나리오를 설명하며, 실무 정합성 보장 방안을 기술함
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 본문, 표 헤더·셀, 요약, 결론의 전체 맞춤법 및 한국어 표현 자연스러움을 검사하고 5회 완독을 통과함

## Ⅰ. 개요

- **정의/개념**: 읽기 이상 현상은 동시 실행되는 트랜잭션 간 격리성 부족으로 인해 특정 트랜잭션의 미커밋 변경이나 중도 갱신/삽입이 다른 트랜잭션의 조회 일관성을 해치는 오류임
- **배경/필요성**: 데이터베이스의 정합성 오류로 인한 비즈니스 오판단과 집계 누락을 원천 차단하기 위해 읽기 이상 유형별 원인 분석과 격리 경계 식별이 필요함

### 쉽게 이해하기 (학습용)
- 여러 명의 전원이 하나의 도화지에 그림을 동시에 그릴 때, 상대방이 칠하다 만 물감이 묻거나 그림이 멋대로 갱신되어 스케치가 뒤죽박죽 꼬이는 현상임

## Ⅱ. 특징

- 트랜잭션이 갱신 중인 단일 데이터 행을 읽는 오류(Dirty Read, Non-Repeatable Read)와 범위 조건을 조회하는 오류(Phantom Read)로 구분됨
- 이상 현상의 발현 범위는 동시 트랜잭션의 커밋 여부와 SQL 연산자 유형(UPDATE, INSERT, DELETE)에 밀접하게 종속됨
- 데이터베이스 성능 효율을 위해 일부 이상 현상을 의도적으로 허용하는 하위 격리 수준 설계를 적용하기도 함
- 이상 현상은 조회 오류처럼 보이지만 원인은 격리 수준과 잠금 범위 설계의 불일치에 있음

### 쉽게 이해하기 (학습용)
- 언제 수정이 일어나는가(커밋 전 vs 후)와 무엇이 추가되는가(행 값 수정 vs 새로운 행 삽입)에 따라 버그의 양상이 다르게 나타남

## Ⅲ. 종류 및 비교

| 판단 기준 | Dirty Read | Non-Repeatable Read | Phantom Read |
|:---|:---|:---|:---|
| 발생 원인 | 타 트랜잭션이 갱신한 미커밋 데이터를 조회함 | 타 트랜잭션이 조회 대상 행을 갱신·커밋함 | 타 트랜잭션이 범위 내에 행을 삽입·삭제·커밋함 |
| 깨지는 결과 | 롤백 대상 데이터를 기정사실로 인지하여 오판단함 | 동일 트랜잭션 내 단일 행의 재조회 값이 일치하지 않음 | 동일 범위 재조회 시 대상 행 수가 증감하거나 변경됨 |
| 주 방지 수단 | Read Committed 수준 적용 | Repeatable Read 수준 또는 Undo 스냅샷 조회 | Serializable 수준 적용 및 인덱스 범위 잠금 |

> 요약: Dirty Read는 미커밋 값, Non-Repeatable Read는 같은 행의 값, Phantom Read는 조건에 맞는 행 집합을 바꿈.

### 쉽게 이해하기 (학습용)
- 남이 낙서하고 지울 글을 본 경우(Dirty), 방금 확인했던 내 글이 바뀐 경우(Repeatable), 안 보이던 투명 인간 행이 갑자기 튀어나오는 경우(Phantom)로 비교됨

## Ⅳ. 설계 요소 및 구조

```text
+-------------------------------------------------------------+
|                     읽기 이상 현상 발생 구조                |
+-------------------------------------------------------------+
        │                              │
        ▼                              ▼
+───────────────────────+      +───────────────────────+
|   1. 단일 행 이상     |      |   2. 범위 행 이상     |
|   - Dirty Read        |      |   - Phantom Read      |
|   - Non-Repeatable    |      |   - 범위 조회 도중    |
|     (갱신/삭제 대상)  |      |     신규 행 삽입/삭제 |
+───────────────────────+      +───────────────────────+
        │                              │
        +──────────────┬───────────────+
                       ▼
+─────────────────────────────────────────────────────────────+
|                     3. DB 엔진 격리 레이어                  |
|   - Read View (Undo 로그 기록 조회)                         |
|   - 락 매니저 (행 공유/배타 잠금 및 갭 락 통제)              |
+-------------------------------------------------------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 조회 시점 | 동일 트랜잭션 내에서 한 번만 조회하는지, 동일 조건으로 다시 조회하는지 결정하는 읽기 생명주기 |
| 동시 변경 작업 | 타 트랜잭션이 백그라운드에서 수행하는 쓰기(INSERT/UPDATE/DELETE) 및 롤백 활동 |
| 격리 레이어 | 이상 현상 방지를 위해 동작하는 데이터베이스 내부의 스냅샷 뷰 및 잠금 처리 엔진 |
| 비즈니스 리스크 | 일관성 붕괴로 인해 초래되는 잔액 오류, 승인 프로세스 중복, 통계 누락 등 실무적 손실 |

> 요약: 조회 시점과 동시 갱신·삽입·삭제 범위에 따라 값 또는 결과 집합의 읽기 이상이 발생함.

### 쉽게 이해하기 (학습용)
- 트랜잭션이 데이터를 읽을 때, 외부에서 이루어지는 쓰기 시점과 충돌하지 않도록 내부 락 매니저가 격리 방패를 제공하는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
[트랜잭션 A: 데이터 조회] 
         │
         ▼
[트랜잭션 B: 데이터 변경] ── (UPDATE / INSERT 수행 및 커밋 또는 롤백)
         │
         ▼
[트랜잭션 A: 동일 데이터 재조회] 
         │
         ▼
[결과 불일치 발생] ── (Dirty Read / Non-Repeatable Read / Phantom Read 감지)
```

1. **첫 번째 조회 수행**: 트랜잭션 A가 특정 행의 값 또는 범위 조회를 수행하여 첫 번째 결과셋을 확보함
2. **동시 변경 작업**: 트랜잭션 B가 트랜잭션 A가 읽은 데이터나 범위 내에 UPDATE, INSERT, DELETE 연산을 진행함
3. **동일 조건 재조회**: 트랜잭션 A가 비즈니스 로직 처리 도중 동일한 조건으로 두 번째 조회를 실행함
4. **결과 불일치 판정**: 변경 데이터가 커밋되었거나 롤백되었는지에 따라 이상 현상(Dirty, Non-Repeatable, Phantom)이 성립하여 로직 오류를 발생시킴

> 요약: 첫 조회 뒤 동시 변경이 발생하면 재조회 결과의 값·행 집합 차이로 이상 유형을 판정함.

### 쉽게 이해하기 (학습용)
- 물건 재고를 확인한 뒤 결제창을 띄우는 찰나에 다른 사람이 재고를 가로채어, 결제를 누르니 이미 재고가 사라지고 없는 상황의 발생 절차임

## Ⅵ. 실무 사례

1. 재고 예약 DB는 Repeatable Read를 적용하고 일관성 오류·재시도 성공률을 확인함
2. 정산 집계 DB는 범위 잠금이나 Serializable을 적용하고 집계 불일치 건수·평균 응답 시간을 확인함

### 쉽게 이해하기 (학습용)
- 선착순 예약 시 예약자 명단이 도중에 바뀌지 않도록 통제하고, 전체 매출 집계 시에는 집계 중간에 새 결제 건이 끼어들지 못하게 막음

## Ⅶ. 결론

- 읽기 이상 현상은 값·행 집합의 허용 불일치를 기준으로 격리 수준과 범위 잠금을 선택하여 해결함
- 완벽한 이상 방지를 위해 과도하게 높은 격리 수준을 남용하기보다는, 응용 애플리케이션의 재시도 패턴 설계와 분산 캐싱 기법을 융합하여 전체 처리 속도를 확보하는 것이 바람직함

### 쉽게 이해하기 (학습용)
- 무조건 완전 격리(Serializable)만 고집하기보다, 상황에 맞는 똑똑한 잠금 설정과 재시도 로직을 조합하는 것이 고성능 시스템의 핵심임
