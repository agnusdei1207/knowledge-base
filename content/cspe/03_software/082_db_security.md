## Ⅰ. 개요
- 허가되지 않은 접근으로부터 데이터를 보호하고 무결성과 기밀성을 유지하는 체계임.
- 사용자 인증, 접근 제어, 암호화, 감사(Audit) 등의 기술적 수단을 포함함.
- 출제 의도: 데이터 보호를 위한 계층적 보안 모델과 관련 법규 준수 역량 확인.

## Ⅱ. 구성요소
- 보안 3요소 및 제어 기법
[Authentication] -> [Authorization] -> [Audit]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| RBAC | 역할(Role) 기반으로 권한을 부여하고 관리함 | 직급별 열람 제한 |
| MAC | 보안 등급에 따라 엄격하게 접근을 제어함 | 군대 비밀 등급 |
| TDE | 데이터 파일 자체를 암호화하여 저장함 (저장 시 암호화) | 금고 보관 |
> 요약: 누구(Who)인지 확인하고 무엇(What)을 할지 제어하며 기록(Log)함.

## Ⅲ. 절차
- DB 보안 강화 프로세스
[Policy Setup] -> [User Auth] -> [Access Control] -> [Monitoring]

1. 정책 수립: 데이터 중요도 분류 및 접근 권한 최소화 원칙 수립함.
2. 인증 강화: MFA(다요소 인증) 및 강력한 패스워드 정책 적용함.
3. 접근 통제: 뷰(View)를 통한 간접 접근 유도 및 SQL 인젝션 방지함.
4. 상시 감사: 주요 쿼리 실행 이력을 기록하고 이상 징후를 실시간 탐지함.
> 요약: 정책 기반의 인증과 통제를 수행하고 상시 감시 체계를 가동함.

## Ⅳ. 문제점
- 과도한 암호화 및 감사 로그 기록으로 인한 시스템 성능 저하.

## Ⅴ. 개선방안
- 하드웨어 가속 암호화 기술 사용 및 머신러닝 기반 이상 행위 탐지(UEBA).

## Ⅵ. 전망
- 제로 트러스트(Zero Trust) 아키텍처 기반의 상시 검증 보안 모델 확산.
- 데이터 주권 보호를 위한 동형 암호화(Homomorphic Encryption) 실용화 연구 가속.
