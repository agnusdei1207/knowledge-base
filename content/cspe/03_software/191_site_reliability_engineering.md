## 미리 알고가기

- SRE는 소프트웨어 공학 기법을 서비스 운영에 적용해 신뢰성과 변경 속도를 함께 관리함
- SLI는 사용자 관점의 서비스 동작을 측정한 값이고 SLO는 목표 수준임
- 오류 예산은 SLO가 허용한 실패량이며 변경과 신뢰성 작업의 우선순위를 조정함
- Toil은 수동·반복·자동화 가능하고 서비스 성장에 비례해 늘어나는 운영 작업임
- 증상 기반 경보는 사용자 영향이 발생한 SLI·오류 예산 소진율을 기준으로 온콜을 호출함
- 사후 분석은 개인을 비난하지 않고 사건 원인·영향·재발 완화 조치를 기록함

## 작성 근거(검토용)

- SRE는 SLO·오류 예산, 자동화·Toil, 관측·경보, 사고 대응·사후 분석을 핵심 축으로 설명함
- 비교표는 절차 중심 운영과 SRE의 목표·변경·반복 작업·경보·사고 학습 방식을 대비함
- 서비스 릴리스와 온콜 운영에서 오류 예산·MTTR·Toil 비율을 검증함

## Ⅰ. 개요

- **정의/개념**: SRE는 사용자 관점 SLO와 오류 예산을 기준으로 자동화·변경 관리·사고 대응에 소프트웨어 공학을 적용하는 운영 방식임
- **배경/필요성**: 기능 배포와 신뢰성 확보의 우선순위를 감각이 아닌 서비스 측정값으로 결정하기 위해 공통 운영 기준이 필요함

## Ⅱ. 특징

- 사용자 경험을 나타내는 SLI와 기간별 SLO로 신뢰성 목표를 수치화함
- 오류 예산 잔여량과 소진율로 배포 지속·완화·중단 조건을 정함
- 반복 운영 작업은 자동화하고 Toil 비율과 작업량을 관리함
- 증상 기반 경보·온콜·사후 분석으로 탐지부터 학습까지 운영 피드백을 연결함

## Ⅲ. 종류 및 비교

| 판단 기준 | 절차 중심 운영 | SRE |
|:---|:---|:---|
| 신뢰성 목표 | 가동 여부·장애 건수 중심 | 사용자 SLI·SLO 중심 |
| 변경 판단 | 변경 일정과 승인 절차 중심 | 오류 예산 잔여량과 변경 위험 중심 |
| 반복 작업 | 운영 절차서와 수동 조치로 수행 | 코드·자동화로 Toil을 줄임 |
| 경보 기준 | 자원 임계치·개별 이벤트 중심 | 사용자 증상·오류 예산 소진율 중심 |
| 사고 대응 | 복구와 원인 보고 중심 | 복구·사후 분석·개선 항목까지 연결 |
| 책임 구조 | 개발과 운영 역할 분리 | 개발·운영이 서비스 신뢰성 목표 공유 |

> 요약: SRE는 사용자 SLO와 오류 예산을 공통 기준으로 삼아 변경·운영·사고 대응을 조정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SLI·SLO | 사용자 관점의 성공·지연·가용성 측정값과 목표를 정의함 |
| 오류 예산 정책 | 예산 소진 상태에 따른 배포·신뢰성 작업 조건을 정함 |
| 관측·경보 | SLI와 소진율을 계산하고 사용자 영향에 따라 온콜을 호출함 |
| 자동화·Toil 관리 | 반복 작업을 코드화하고 수동 운영 작업의 비율을 추적함 |
| 사고 대응 | 역할·에스컬레이션·복구 절차로 서비스 영향을 줄임 |
| 사후 분석 | 원인·영향·탐지·복구·개선 항목과 담당자를 기록함 |

```text
사용자 SLI -> SLO·오류 예산 -> 배포·운영 판단
     ^                              |
     +---- 관측·사고 대응·사후 분석 -+
```

> 요약: SLI와 오류 예산이 변경 판단을 만들고 사고 대응 결과가 자동화와 SLO 개선으로 돌아옴.

## Ⅵ. 실무 사례

1. API 릴리스는 오류 예산 소진율로 배포를 조정하고 SLO 준수율·변경 실패율을 확인함
2. 온콜 업무는 반복 복구를 자동화하고 MTTR·Toil 비율을 확인함

## Ⅶ. 결론

- SRE는 사용자 SLO와 오류 예산을 기준으로 배포 위험·Toil·사고 대응의 우선순위를 결정함
