## Ⅰ. 개요
- **정의**: API 키, 인증서, 비밀번호 등 민감 정보를 안전하게 저장·배포·회전하는 체계
- **배경/필요성**: 소스코드나 설정 파일에 하드코딩된 시크릿이 유출되면 시스템 전체가 침해 대상이 됨
- **비유**: 금고에 열쇠를 보관하고 필요할 때만 인가된 사람에게 한시적으로 빌려주는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 민감정보 생명주기 관리 이해 | 동적 시크릿·자동 회전·접근 감사 | 암호화 저장과 시크릿 관리 혼동 금지 |

> 요약: 민감 정보의 저장·배포·회전·폐기 전 생명주기를 중앙 관리하는 보안 체계임

## Ⅱ. 구성요소
```text
[Application] --request--> [Secrets Engine] --fetch--> [Encrypted Store]
                                |
                                v
                         [Audit Log / Rotation]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Secrets Engine | 시크릿 생성·회전·폐기를 수행하는 핵심 엔진 | 금고 관리인 |
| Encrypted Store | 시크릿을 암호화하여 저장하는 백엔드(KMS 연동) | 금고 내부 |
| Access Policy | 역할 기반으로 시크릿 접근 범위를 제어하는 정책 | 열쇠 대여 규칙 |
| Audit Log | 시크릿 접근·변경 이력을 기록하는 감사 로그 | 금고 출입 장부 |

> 요약: 시크릿 엔진이 암호화 저장소와 접근 정책을 기반으로 민감 정보 생명주기를 관리함

## Ⅲ. 절차
```text
Register --> Store/Encrypt --> Distribute --> Rotate/Revoke
```
- 1단계: 시크릿을 중앙 저장소에 등록하고 접근 정책 설정
- 2단계: KMS 연동 암호화 후 안전한 백엔드에 저장
- 3단계: 인가된 애플리케이션에 런타임 시 동적으로 주입
- 4단계: TTL 만료 시 자동 회전 또는 폐기 수행

> 요약: 등록·암호화 저장·동적 배포·자동 회전의 4단계로 시크릿 생명주기를 관리함

## Ⅳ. 문제점
- 시크릿 스프롤: 여러 시스템에 시크릿 사본이 산재하여 일괄 회전·폐기가 곤란함
- 정적 시크릿 장기 사용: 회전 없이 동일 키를 장기간 사용하면 유출 시 피해 범위 확대
- 감사 사각지대: 시크릿 접근 로그가 미비하면 유출 경로 추적이 불가함

> 요약: 시크릿 산재, 장기 사용, 감사 미비가 주요 위험 요인임

## Ⅴ. 개선방안
1. 단기: 중앙 집중형 시크릿 저장소(Vault 등) 도입으로 산재 문제 해소
2. 중기: 동적 시크릿 발급 및 TTL 기반 자동 회전 체계 적용
3. 장기: 모든 시크릿 접근에 대한 실시간 감사 로그 및 이상 탐지 연동

> 요약: 중앙화, 동적 발급·회전, 실시간 감사로 시크릿 보안 수준을 체계적으로 강화함

## Ⅵ. 전망
- 발전 방향: 제로트러스트 아키텍처 확산과 함께 시크릿리스(Secretless) 인증 패턴 부상
- 기술사적 판단: 클라우드 네이티브 환경에서 시크릿 관리는 보안 기본 요건
- 기술사 제언: 시크릿 관리를 CI/CD 파이프라인에 내재화하여 배포 시점 자동 주입 필요
