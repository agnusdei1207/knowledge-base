## Ⅰ. 개요
- 정의: 둘 이상의 프로세스가 서로 상대방이 가진 자원 해제를 기다려 진행하지 못하는 상태
- 배경: 여러 프로세스가 제한된 자원을 서로 다른 순서로 점유·요청하면 순환 대기가 발생할 수 있음
- 출제 의도: 발생 4조건과 예방, 회피, 발견, 복구 방식의 차이 판단

## Ⅱ. 구성요소
```
[ P1 ] --(Hold)--> [ R1 ] <--(Request)-- [ P2 ]
  ^                                        |
  |                                        v
(Request) <------- [ R2 ] <------------(Hold)
```
| 구성요소 | 설명 | 제거 기준 |
| :--- | :--- | :--- |
| 상호 배제 | 한 번에 한 프로세스만 자원을 사용함 | 공유 가능 자원 전환 |
| 점유와 대기 | 자원을 가진 채 다른 자원을 추가로 요청함 | 일괄 요청 |
| 비선점 | 다른 프로세스의 자원을 강제로 뺏을 수 없음 | 선점 가능 자원 설계 |
| 환형 대기 | 프로세스들이 원형으로 자원을 대기함 | 전역 자원 순서 |
> 요약: 위 4가지 조건이 동시에 충족될 때 교착상태가 발생함.

## Ⅲ. 절차
```
[Resource Request] -> [Cycle Check] -> [Deadlock?] -> [Recovery Action]
```
1. 자원 할당 그래프(RAG)를 통해 프로세스와 자원 간의 관계를 모델링함
2. 단일 인스턴스 자원은 자원 할당 그래프의 사이클을, 다중 인스턴스 자원은 대기·할당 벡터를 검사함
3. 교착상태 확인 시 종료, 롤백, 자원 회수 중 복구 방식을 결정
4. 시스템을 안정 상태(Safe State)로 되돌리기 위한 복구 수행
> 요약: 자원 대기 관계에서 교착상태를 탐지한 뒤 프로세스 종료·롤백·자원 선점으로 순환 대기를 해소함.

## Ⅳ. 문제점
- 원인: 예방 기법은 자원 요청을 제한하므로 동시 실행 가능한 작업 수가 줄어듦
- 원인: 발견 및 복구 기법은 주기적 탐지 비용과 복구 중단 시간이 발생함

## Ⅴ. 개선방안
- (단기) 자원 요청 순서를 전역적으로 정의하여 환형 대기 조건 제거
- (중기) 은행가 알고리즘 등 회피(Avoidance) 방식으로 안전 순서 존재 여부 확인
- (장기) 타임아웃 기반 자원 회수와 트랜잭션 롤백으로 복구 중단 시간 관리

## Ⅵ. 전망
- 대규모 분산 데이터베이스에서는 노드 간 대기 그래프를 수집하는 분산 추적이 필요함
- 운영 환경에서는 락 대기 시간과 트랜잭션 의존 관계를 관측해 교착 가능성을 조기에 탐지함

## 작성 근거(검토용)

- 교착상태는 끝없는 대기보다 자원 해제를 기다려 진행하지 못하는 상태로 쓰는 편이 원인과 조건을 정확히 보여줌
- 4조건 표는 예시가 아니라 어떤 조건을 제거해야 하는지로 정리해야 예방, 회피, 발견, 복구 절로 이어짐
