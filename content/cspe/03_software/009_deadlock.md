## Ⅰ. 개요
- 정의: 둘 이상의 프로세스가 서로 상대방이 가진 자원을 기다리며 무한 대기에 빠진 상태
- 배경: 제한된 자원을 여러 프로세스가 동시에 공유하여 사용하는 복잡한 환경에서 발생
- 출제 의도: 발생 4조건 분석 및 예방/회피/발견/복구의 체계적 대응 역량 평가

## Ⅱ. 구성요소
```
[ P1 ] --(Hold)--> [ R1 ] <--(Request)-- [ P2 ]
  ^                                        |
  |                                        v
(Request) <------- [ R2 ] <------------(Hold)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 상호 배제 | 한 번에 한 프로세스만 자원을 사용할 수 있음 | 1인용 도구 |
| 점유와 대기 | 자원을 가진 채 다른 자원을 추가로 요청함 | 하나 쥐고 욕심 |
| 비선점 | 다른 프로세스의 자원을 강제로 뺏을 수 없음 | 양보 없음 |
| 환형 대기 | 프로세스들이 원형으로 자원을 대기함 | 꼬리에 꼬리 물기 |
> 요약: 위 4가지 조건이 동시에 충족될 때 교착상태가 발생함.

## Ⅲ. 절차
```
[Resource Request] -> [Cycle Check] -> [Deadlock?] -> [Recovery Action]
```
1. 자원 할당 그래프(RAG)를 통해 프로세스와 자원 간의 관계를 모델링함
2. 그래프 내에 사이클(Cycle)이 존재하는지 DFS/BFS 알고리즘 등으로 탐색
3. 교착상태 확인 시 복구 전략(프로세스 종료 또는 자원 선점) 결정
4. 시스템을 안정 상태(Safe State)로 되돌리기 위한 복구 수행
> 요약: 상태 감시와 탐색 알고리즘을 통해 문제 상황을 인지하고 해결함.

## Ⅳ. 문제점
- 원인: 예방 기법은 자원 이용률을 현저히 저하시켜 시스템 효율성이 떨어짐
- 원인: 발견 및 복구 기법은 주기적인 검사로 인해 시스템에 추가적인 오버헤드 부여

## Ⅴ. 개선방안
- (단기) 자원 요청 순서를 전역적으로 정의하여 환형 대기 조건 원천 차단
- (중기) 은행가 알고리즘 등 회피(Avoidance) 전략을 통한 안전 상태 유지
- (장기) 타임아웃 기반 자원 회수 및 트랜잭션 롤백 메커니즘을 통한 자동 복구 강화

## Ⅵ. 전망
- 대규모 분산 데이터베이스 환경에서 글로벌 데드락을 감지하기 위한 분산 추적 기술 중요성 증대
- AI 기반 이상 탐지 기술을 활용하여 데드락 발생 징후를 사전에 예측하고 회피하는 지능형 관리 모델 확산
