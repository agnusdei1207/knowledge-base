# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 교착상태(Deadlock)는 둘 이상의 프로세스가 **서로가 쥔 자원을 상대가 놓기만 기다리며 아무도 진행하지 못하는** 영구 대기 상태로, 코프만(Coffman)의 4대 조건이 동시에 성립할 때 발생한다.
- **왜 필요한가**: 자원(락·메모리·DB 커넥션)은 유한한데 여러 프로세스가 동시에 여러 개를 잡으려 하면, 서로 절반씩 쥔 채 상대의 것을 기다리는 순환이 생길 수 있다. 이 순환은 저절로 풀리지 않아 시스템이 멈추므로, 발생 조건을 알고 예방·회피·탐지·복구 전략을 갖춰야 한다.
- **핵심 직관**: 좁은 외길에서 마주 오는 두 차가 서로 "네가 먼저 물러나라"며 버티는 상황이다. 둘 다 후진하지 않으면(자원을 놓지 않으면) 영원히 못 지나간다. 누군가 양보(선점)하거나, 애초에 한 방향만 통행하게(예방) 규칙을 세워야 풀린다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 답안용에 나오는 코프만 4조건과 4대 전략 용어를 비유와 함께 먼저 세운다. 맨 위가 이 주제의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 교착상태 (상위 키워드) | 상호 자원 대기로 모두가 영구 정지한 상태 | 외길에서 서로 안 비키는 두 차 |
| 상호 배제 (Mutual Exclusion) | 한 자원을 한 번에 한 프로세스만 점유 가능 | 화장실 한 칸은 한 명만 |
| 점유와 대기 (Hold and Wait) | 자원을 쥔 채로 다른 자원을 추가로 기다림 | 한 손에 물건 들고 다른 것도 달라며 대기 |
| 비선점 (No Preemption) | 쥔 자원을 강제로 뺏을 수 없음 | 남이 든 물건을 억지로 못 뺏음 |
| 환형 대기 (Circular Wait) | 대기 관계가 원을 이룸(P1→P2→…→P1) | 서로 꼬리를 무는 원형 대기 줄 |
| 코프만 조건 (Coffman Conditions) | 위 4가지, 동시 성립이 교착 발생의 필요충분 | 교착이 성립하는 네 개의 자물쇠 |
| 자원 할당 그래프 (RAG) | 프로세스·자원의 요청/할당을 화살표로 표현 | 누가 무엇을 쥐고 무엇을 기다리는지 지도 |
| 예방 (Prevention) | 4조건 중 하나를 원천 봉쇄 | 애초에 외길을 일방통행으로 만듦 |
| 회피 (Avoidance) | 매 요청 시 안전 상태 유지 여부 계산 후 승인 | 사고 안 나는 선에서만 통행 허가(010 참조) |
| 안전 상태 (Safe State) | 모든 프로세스를 끝까지 실행할 순서가 존재 | 결국 모두 빠져나갈 수 있는 배치 |
| 탐지 (Detection) | 교착 발생을 허용하되 주기적으로 검사 | 사고 나면 CCTV로 찾아냄 |
| 복구 (Recovery) | 탐지된 교착을 프로세스 종료·자원 선점으로 해소 | 한 차를 강제로 빼서 길 틈 |
| 기아 (Starvation) | 자원에 계속 밀려 특정 작업이 영영 못 받음 (011 참조) | 새치기에 계속 밀려 못 지나가는 차 |

## 깊이 이해
- **배경·문제의식**: 동시성 시스템에서 프로세스가 자원을 하나만 쓰면 문제가 없다. 그러나 트랜잭션이 여러 행(row)에 락을 걸거나, 스레드가 뮤텍스 두 개를 잡는 등 **다중 자원을 순차 획득**하는 순간 순환 대기가 생길 여지가 열린다. 교착은 드물게 발생하지만 한 번 걸리면 저절로 안 풀리고 시스템 전체를 멈춰, 발생 구조와 대응 전략을 반드시 이해해야 한다.
- **작동 원리(어떻게+왜)**: 코프만 4조건이 **동시에** 성립해야 교착이 난다. 이 중 하나라도 깨지면 교착은 불가능하다. 대응 4전략은 이 성질을 각기 다르게 이용한다.
  - 예방: 4조건 중 하나를 설계 단계에서 제거(예: 점유와 대기 제거 → 필요한 자원을 한 번에 모두 요청).
  - 회피: 조건은 놔두되 매 요청마다 승인 후에도 안전 상태가 유지되는지 계산해 위험한 요청만 거절(은행원 알고리즘, 상세는 010 참조).
  - 탐지·복구: 교착을 일단 허용하고 자원 할당 그래프의 순환을 주기적으로 검사, 발견 시 프로세스 종료나 자원 선점으로 원을 끊음.
- **비유**: 사거리 교차로다. 예방은 신호등·일방통행으로 애초에 엉킴을 못 만들게 하고, 회피는 교통경찰이 진입 전 "저 차가 들어오면 막힐까"를 판단해 통제하며, 탐지·복구는 일단 통행시키다 엉키면 견인차로 한 대를 빼낸다. 예방은 보수적(자원 활용 저하), 탐지·복구는 낙관적(사후 비용)이다.
- **구체 예시**: 스레드 T1이 뮤텍스 A→B 순서로 잡고, T2가 B→A 순서로 잡으면, T1이 A를 쥐고 B를 기다리는 동안 T2가 B를 쥐고 A를 기다려 환형 대기가 성립한다. 실무의 표준 예방책은 **락 순서(lock ordering)를 전역으로 통일**해 항상 A→B로만 잡게 하는 것으로, 이는 환형 대기 조건을 깨는 방식이다.
- **흔한 오해·주의점**: (1) 교착과 기아는 다르다. 교착은 관련 프로세스가 **모두** 영구 정지하지만, 기아(011 참조)는 시스템은 돌아가는데 특정 프로세스만 계속 밀린다. (2) "불안전 상태 = 교착"이 아니다. 불안전은 교착 위험 지대일 뿐 아직 발생은 아니다(010 참조). (3) 상용 OS 대부분은 회피(은행원)를 안 쓰고, 교착을 무시하거나(타조 알고리즘) 탐지·복구·재시작에 맡긴다 — 회피 비용이 실측 이득보다 크기 때문이다.

## 연결 개념
- 은행원 알고리즘(010 참조) — 회피 전략의 대표 구현, 안전 상태 계산의 상세
- 기아와 에이징(011 참조) — 교착과 구분되는 또 다른 무한 대기와 그 해소
- 세마포어·뮤텍스·모니터(012 참조) — 교착을 유발하는 락 획득과 순서 통제 수단

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 교착상태는 코프만 4조건(상호 배제·점유와 대기·비선점·환형 대기)이 동시 성립할 때 발생하는 상호 자원 대기 상태임.
> 2. **가치**: 예방·회피·탐지·복구 4전략은 4조건 성립을 각기 다른 시점(설계·요청·사후)에 통제해 시스템 정지를 방지함.
> 3. **판단 포인트**: 예방은 자원 활용을 희생하고 탐지·복구는 사후 비용을 지불하므로, 발생 빈도·중요도에 따라 전략을 선택해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 교착 발생 조건 이해 | 코프만 4조건과 동시 성립 필요성 | 4조건 중 일부 누락 |
| 4대 대응 전략 구분 | 예방·회피·탐지·복구의 통제 시점 차이 | 예방과 회피 혼동 |
| 전략별 트레이드오프 판단 | 자원 활용 저하 vs 사후 비용 | 교착과 기아 개념 혼동 |

> 요약: 4조건과 4전략을 정확히 대응시키고, 각 전략이 언제 무엇을 희생하는지 트레이드오프로 선택 기준을 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 둘 이상 프로세스가 서로의 자원을 대기하며 모두 진행하지 못하는 영구 대기 상태임
- 배경: 다중 자원을 순차 획득하는 동시성 환경에서 대기 관계가 순환을 이루면 저절로 풀리지 않음
- 필요성: 한 번 걸리면 시스템 전체가 정지하므로 발생 조건 파악과 예방·회피·탐지·복구 대응이 필수임

## Ⅱ. 구조 및 구성요소

선형 구조도 (환형 대기가 형성되는 구조):

    P1 -자원 R1 점유-> R2 요청(대기)
    P2 -자원 R2 점유-> R1 요청(대기)
      -> 대기 관계가 원(P1 -> P2 -> P1)을 이룸 = 환형 대기 성립

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 상호 배제 | 자원을 한 번에 한 프로세스만 점유 | 공유 불가 자원에서 성립 |
| 점유와 대기 | 자원을 쥔 채 추가 자원 대기 | 한 번에 전량 요청으로 제거 가능 |
| 비선점 | 쥔 자원을 강제 회수 불가 | 선점 허용으로 제거 가능 |
| 환형 대기 | 대기 관계가 순환 형성 | 자원 순서 부여로 제거 가능 |

> 요약: 코프만 4조건이 동시에 성립할 때만 교착이 발생하며, 이 중 하나를 깨는 것이 예방의 핵심 원리임.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도 (대응 전략 선택 경로):

    자원 요청 발생 -> 전략 결정
      -> [예방] 4조건 중 하나를 사전 차단 -> 교착 원천 불가
      -> [회피] 승인 시 안전 상태 유지 계산 -> 위험 요청만 거절(010 참조)
      -> [탐지·복구] 허용 후 순환 검사 -> 발견 시 종료·선점으로 해소

- 1단계 [예방]: 상호 배제·점유와 대기·비선점·환형 대기 중 하나를 설계로 제거해 교착을 원천 차단함
- 2단계 [회피]: 자원 요청 시점마다 승인 후에도 안전 상태가 유지되는지 계산해 불안전으로 가는 요청만 거절함
- 3단계 [탐지]: 교착을 허용하되 자원 할당 그래프의 순환을 주기적으로 검사해 발생을 식별함
- 4단계 [복구]: 탐지 시 관련 프로세스를 종료하거나 자원을 선점(롤백)해 환형 대기를 끊음

> 요약: 예방은 조건을 사전 차단, 회피는 요청 시점 계산, 탐지·복구는 사후 해소로 각기 다른 시점에 교착을 통제함.

## Ⅳ. 특징

- 조건 동시성: 코프만 4조건이 모두 성립해야 발생하며, 하나만 깨도 교착은 불가능함
- 자기 비해소성: 외부 개입 없이는 스스로 풀리지 않아 반드시 복구 행위가 필요함
- 예방의 보수성: 조건을 미리 차단해 확실하나 자원 활용률·병행성이 저하됨
- 탐지·복구의 낙관성: 평상시 오버헤드가 없으나 발생 시 롤백·재시작 비용을 지불함
- 기아와의 구별: 교착은 다수의 상호 정지, 기아는 단일 프로세스의 지속적 배제(011 참조)

## Ⅴ. 심화 비교 및 적용 판단

예방·회피·탐지복구 3대 전략을 시점·오버헤드·자원활용 축으로 대조함(회피 상세는 010 참조).

| 구분 | 예방 (Prevention) | 회피 (Avoidance) | 탐지·복구 (Detection & Recovery) |
|:---|:---|:---|:---|
| 통제 시점 | 설계 단계(사전) | 자원 요청 시점(실시간 계산) | 발생 후(사후) |
| 핵심 기법 | 4조건 중 하나 제거 | 은행원 알고리즘·안전 상태 판정 | RAG 순환 탐지·종료/선점 |
| 자원 활용률 | 낮음(보수적 제약) | 중간(Max 사전 선언 필요) | 높음(평상시 무제약) |
| 오버헤드 | 낮음(런타임 부담 적음) | 높음(매 요청 O(m·n²) 계산) | 탐지 주기·복구 비용 |

> 요약: 교착 발생이 드물면 탐지·복구 또는 무시가 경제적이고, 치명적 시스템은 예방으로 원천 차단함.

**리스크·대응:**
- 락 순서 불일치 — 스레드마다 상반된 락 획득 순서로 환형 대기 — 전역 락 순서(lock ordering) 강제로 환형 대기 제거
- 복구 시 기아 — 매번 같은 프로세스를 희생자로 선정 — 롤백 횟수·우선순위 반영해 희생자 순환 선정
- 회피 계산 부담 — 매 요청 안전 상태 계산 비용 과다 — 자원 사용량 고정 환경(RTOS)에만 제한 적용(010 참조)

**점검 지표:**
- 성능: 교착 탐지 주기·1회 검사 비용, 자원 대기 시간
- 운영: 교착 발생 빈도, 복구 롤백 건수(Victim Count)

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 락 순서 통일: 다중 뮤텍스·DB 락 획득 시 전역 순서(예: 자원 ID 오름차순)를 강제해 환형 대기를 구조적으로 제거함
2. 타임아웃·재시도: DB 트랜잭션에 lock wait timeout과 지수 백오프 재시도를 두어 교착을 탐지·자동 해소함(MySQL InnoDB는 순환 탐지 후 자동 롤백)
3. 자원 일괄 획득: 필요한 락을 한 번에 모두 시도(tryLock all-or-nothing)해 점유와 대기 조건을 차단함

**결론:**
- 기술사 판단: 교착 발생이 드물고 재시도가 저렴한 일반 시스템은 탐지·복구·타임아웃을, 정지가 치명적인 안전·실시간 시스템은 예방(락 순서·일괄 획득)을 택함
- 향후 방향: 분산 트랜잭션·마이크로서비스 확산으로 단일 노드 탐지가 어려워져, 사가·타임아웃 기반 낙관적 해소와 무공유(share-nothing) 설계로 교착 여지를 줄이는 방향이 강화됨
