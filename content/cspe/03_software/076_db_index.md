## Ⅰ. 개요
- 데이터 검색 성능을 높이기 위해 데이터의 위치 정보를 별도로 관리하는 자료구조임.
- 풀 테이블 스캔을 피하고 O(log N) 이하의 성능을 확보하는 것이 목적임.
- 출제 의도: 인덱스 구조별 장단점과 선택 기준, 성능 영향도 평가 능력 확인.

## Ⅱ. 구성요소
- 인덱스 주요 구조
[Root Node] -> [Branch Node] -> [Leaf Node: Pointer to Data]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| B-Tree Index | 밸런싱된 트리 구조로 범위 검색에 유리함 | 도서관 십진분류표 |
| Hash Index | 키값의 해시 결과로 직접 접근, 등호 비교 최적 | 사물함 번호 찾기 |
| Bitmap Index | 비트 열로 상태 저장, 낮은 Cardinality에 유리 | 체크박스 필터링 |
> 요약: 정렬된 트리 혹은 해시 맵을 통해 검색 경로를 단축함.

## Ⅲ. 절차
- B-Tree 탐색 과정
[Search Key] -> (Root) -> (Branch Selection) -> (Leaf Arrival) -> [Data Access]

1. 루트 노드 비교: 검색값과 루트의 키 범위를 대조함.
2. 분기 이동: 자식 노드 포인터를 따라 하위 레벨로 하강함.
3. 리프 노드 도달: 실제 데이터가 저장된 주소(RID)를 획득함.
4. 데이터 추출: 획득한 주소로 디스크 I/O를 수행하여 레코드 읽음.
> 요약: 트리의 높이(Height)만큼의 노드 방문으로 목표 데이터에 도달함.

## Ⅳ. 문제점
- 데이터 추가/수정/삭제 시 인덱스 갱신 오버헤드 및 저장 공간 추가 소요.

## Ⅴ. 개선방안
- 인덱스 재구성(Rebuild) 및 인덱스 스캔만으로 쿼리 완료(Covering Index) 유도.

## Ⅵ. 전망
- 학습형 인덱스(Learned Index) 등 AI를 활용한 데이터 분포 최적화 구조 도입.
- 고성능 NVMe SSD 특성을 반영한 새로운 지연 시간 최적화 인덱스 기술 발전.
