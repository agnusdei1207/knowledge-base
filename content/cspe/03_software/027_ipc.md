## Ⅰ. 개요
- 정의: 독립된 메모리 공간을 가진 프로세스들이 서로 데이터를 주고받는 메커니즘
- 배경: 협력적 작업 처리 및 자원 공유, 모듈화된 시스템 구성 요소 간의 연동 필요
- 출제 의도: 통신 방식의 분류(메모리 공유형 vs 메시지 전달형)와 동기화 문제 이해

## Ⅱ. 구성요소
```
[ Shared Memory ]       [ Message Passing ]       [ Pipe / Socket ]
   P1 --- [RAM] --- P2     P1 --(Queue)--> P2        P1 ===(Pipe)=== P2
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 파이프 | 부모-자식 간 단방향 통신 채널 (Anonymous Pipe) | 확성기 |
| 메시지 큐 | 커널이 관리하는 메시지 연결 리스트 구조 | 우체통 |
| 공유 메모리 | 프로세스들이 공통으로 접근 가능한 메모리 블록 | 게시판 |
> 요약: 커널의 중재 여부와 메모리 직접 접근 여부에 따라 구분됨.

## Ⅲ. 절차
```
[Request IPC] -> [Kernel Obj Create] -> [Data Transfer] -> [Sync (if needed)]
```
1. 통신을 원하는 프로세스가 커널에 IPC 자원(Key, Id 등) 생성을 요청함
2. 송신 프로세스가 메시지를 생성하여 큐에 넣거나 공유 영역에 데이터 기록
3. 커널은 메시지 도달을 알리거나 세마포어로 공유 메모리 접근 순서 제어
4. 수신 프로세스가 데이터를 읽어가고 작업 완료 후 IPC 자원 반납 또는 유지
> 요약: 커널이 제공하는 통로를 통해 데이터를 안전하게 교환함.

## Ⅳ. 문제점
- 원인: 공유 메모리 사용 시 동기화(Sync) 처리가 미흡하면 데이터 오염 발생함
- 원인: 메시지 패싱 방식은 커널을 통한 복사 오버헤드로 대용량 처리 시 성능 한계

## Ⅴ. 개선방안
- (단기) 세마포어(Semaphore) 및 뮤텍스를 결합하여 공유 메모리의 원자성 보장
- (중기) 로컬 통신은 유닉스 도메인 소켓, 원격은 TCP/IP 소켓으로 유연하게 설계
- (장기) 제로 카피(Zero-copy) 전송 기술 및 원격 직접 메모리 접근(RDMA) 활용

## Ⅵ. 전망
- 마이크로서비스 아키텍처(MSA) 확산으로 프로세스 간 통신을 넘어 네트워크 기반 RPC/gRPC 중요성 확대
- 효율적인 데이터 직렬화(Protobuf 등) 기술과 결합하여 IPC 성능 한계를 극복하려는 시도 지속
