## Ⅰ. 개요
- 정의: Software Configuration Management의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Baseline] -> [Identification] -> [Control] -> [Audit] -> [Status]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 베이스라인 | 공식적으로 검토 승인된 산출물 집합 | 기준선 |
| 형상 통제 | 변경 요청에 대한 검토 및 승인 처리 | 출입 통제 |
| CCB | 형상 변경을 결정하는 심의 기구 | 위원회 |

> 요약: SW 생명주기 전반의 산출물을 체계적으로 관리하는 활동임.

## Ⅲ. 절차
- ASCII 흐름도
  Request -> Analysis -> Approve -> Change -> Verify -> Release

1. 형상 식별: 관리 대상(코드, 문서 등) 정의 및 명명 규칙 수립함.
2. 형상 통제: 변경 요청 관리 및 승인 프로세스 운영함.
3. 형상 감사: 베이스라인의 무결성 및 변경 일치성 확인함.
4. 상태 보고: 형상의 변경 이력 및 현재 상태 기록/전파함.

> 요약: 추적성 확보와 버전 혼란 방지를 통한 프로젝트 가시성 향상임.

## Ⅳ. 문제점
- 엄격한 절차 적용 시 개발 유연성 및 속도 저하 발생함.
- 분산 개발 환경에서 중앙 집중형 관리 시 병목 현상 발생함.

## Ⅴ. 개선방안
- 자동화된 SCM 도구 연동으로 절차 간소화 및 실시간 관리함.
- Git 등 분산 형상 관리 도입으로 협업 효율 및 유연성 확보함.

## Ⅵ. 전망
- Infrastructure as Code (IaC) 확산으로 인프라 형상 관리와 통합됨.
- CSF: 개발 문화와 조화되는 유연한 형상 관리 정책 및 도구 활용임.
