## 미리 알고가기

- 컨테이너 이미지는 애플리케이션 실행 파일·라이브러리·설정을 담은 불변 계층 패키지임
- 컨테이너는 이미지에 쓰기 계층과 실행 설정을 더한 격리 프로세스임
- 네임스페이스는 프로세스·네트워크·마운트 등 커널 자원의 가시 범위를 분리함
- cgroup은 컨테이너 프로세스의 CPU·메모리·I/O 사용량을 제한·계측함
- Linux capability는 root 권한을 기능별로 나누어 컨테이너에 필요한 권한만 부여함
- Dockerfile은 이미지 계층과 실행 기본값을 만드는 빌드 명령 문서임
- 레지스트리는 이미지 계층과 태그·다이제스트를 저장하고 배포 노드에 전달함
- 볼륨은 컨테이너 수명과 분리해 데이터를 호스트나 외부 스토리지에 보존함

## 작성 근거(검토용)

- Docker는 이미지의 재현성과 프로세스 격리·자원 제한이 핵심이므로 이미지와 컨테이너 관계를 중심에 둠
- 이미지·컨테이너 비교를 데몬·레지스트리·네임스페이스·cgroup·볼륨 구조와 실행 절차로 연결함
- 제목부터 결론까지 5회 전수 검수하여 이미지와 실행 인스턴스의 상태·수명을 구분함

## Ⅰ. 개요

- **정의/개념**: Docker 컨테이너는 불변 이미지의 애플리케이션을 네임스페이스·cgroup으로 격리해 실행하는 프로세스임
- **배경/필요성**: 개발·시험·운영 환경의 실행 파일과 의존성을 일치시키기 위해 표준 이미지와 격리 실행 단위가 필요함

## Ⅱ. 특징

- Dockerfile 명령마다 이미지 계층을 만들고 변경 계층만 다시 빌드·전송함
- 컨테이너는 호스트 커널을 공유하면서 프로세스·네트워크·파일시스템 가시 범위를 분리함
- cgroup 제한과 capability 제거로 자원 사용량과 커널 권한 범위를 통제함
- 컨테이너 쓰기 계층은 삭제 시 사라지므로 영속 데이터는 볼륨에 저장함

## Ⅲ. 이미지와 컨테이너 비교

| 판단 기준 | 이미지 | 컨테이너 |
|:---|:---|:---|
| 성격 | 실행 환경을 정의한 불변 패키지 | 이미지에서 생성된 실행 프로세스 |
| 저장 구조 | 읽기 전용 계층과 메타데이터 | 이미지 계층과 컨테이너 쓰기 계층 |
| 식별 기준 | 태그 또는 내용 다이제스트 | 컨테이너 ID와 이름 |
| 변경 방식 | 새 계층을 추가해 새 이미지 생성 | 실행 중 쓰기 계층과 메모리 상태 변경 |
| 수명 | 레지스트리·노드에 보관되는 배포 산출물 | 주 프로세스 종료와 함께 실행 상태 종료 |
| 주요 활용 | 빌드·서명·배포 버전 고정 | 애플리케이션 실행·격리·자원 제한 |

> 요약: 이미지는 실행 환경의 불변 원본이고 컨테이너는 이미지에서 만든 격리 프로세스임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| Docker CLI·API | 빌드·실행·조회 요청을 Docker 데몬에 전달함 |
| Docker 데몬 | 이미지·컨테이너·네트워크·볼륨의 수명주기를 관리함 |
| Dockerfile·빌더 | 명령과 빌드 문맥으로 이미지 계층을 생성함 |
| 이미지·레지스트리 | 불변 계층을 저장하고 다이제스트로 배포 대상을 식별함 |
| 네임스페이스·cgroup | 실행 가시 범위와 CPU·메모리·I/O 사용량을 제한함 |
| 네트워크·볼륨 | 서비스 연결과 컨테이너 외부 데이터 보존을 제공함 |

```text
Docker CLI -> Docker 데몬 <-> 이미지 레지스트리
                    |
          이미지 -> 컨테이너 -> 네트워크·볼륨
```

> 요약: 데몬이 레지스트리의 이미지를 받아 격리된 컨테이너와 네트워크·볼륨을 구성함.

## Ⅴ. 컨테이너 실행 흐름

```text
실행 요청 -> 이미지 확인·가져오기 -> 쓰기 계층 생성 -> 격리·자원 설정 -> 주 프로세스 실행
```

1. **실행 요청**: CLI가 이미지·명령·환경 변수·포트·볼륨 설정을 데몬에 전달함
2. **이미지 확인**: 노드에 이미지가 없으면 레지스트리에서 계층과 다이제스트를 가져옴
3. **실행 계층 생성**: 이미지 위에 컨테이너 쓰기 계층과 네트워크 인터페이스를 만듦
4. **격리·자원 설정**: 네임스페이스·cgroup·capability·보안 프로필을 적용함
5. **주 프로세스 실행**: 지정 명령을 실행하고 종료 코드와 로그를 컨테이너 상태에 반영함

> 요약: 이미지 확인 후 쓰기 계층과 격리 경계를 만든 뒤 지정한 주 프로세스를 실행함.

## Ⅵ. 실무 사례

1. API 배포는 이미지 다이제스트를 고정하고 컨테이너 시작시간·롤백 시간을 확인함
2. 빌드 파이프라인은 다단계 빌드를 적용하고 최종 이미지 크기·빌드 시간을 확인함

## Ⅶ. 결론

- Docker는 불변 이미지와 외부 볼륨을 분리하고 격리·자원 제한을 실행 설정으로 관리해야 함
