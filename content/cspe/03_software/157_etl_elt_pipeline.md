## 미리 알고가기

- Extract는 DB·파일·API에서 원천 데이터와 증분 위치를 읽는 단계임
- Transform은 형식·코드·키·품질·업무 규칙을 적용해 목표 데이터로 변환하는 단계임
- Load는 데이터를 목표 저장소의 테이블·파티션·파일로 반영하는 단계임
- ETL은 목표 저장소에 적재하기 전에 별도 처리 계층에서 변환함
- ELT는 원천을 목표 분석 저장소에 먼저 적재하고 그 저장소의 연산으로 변환함
- Pushdown은 필터·조인·집계를 데이터가 있는 엔진에서 실행해 이동량을 줄이는 방식임

## 작성 근거(검토용)

- ETL·ELT는 처리 순서·연산 자원·원천 노출·보존을 핵심 비교축으로 선정함
- 비교표는 두 방식의 실행 순서·연산 위치·원천 노출 범위를 같은 기준으로 대비하고 공통 단계 나열을 반복하지 않음
- 절차는 ETL과 ELT의 실제 데이터 상태 변화가 다르므로 두 흐름을 분리해 제시함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 추출·변환·적재 동사를 대상별로 연결함

## Ⅰ. 개요

- **정의/개념**: ETL·ELT 파이프라인은 원천을 추출·변환·적재하고 처리 엔진·보안·재처리 요구에 따라 변환 위치와 적재 순서를 선택하는 데이터 연계 방식임
- **배경/필요성**: 여러 원천의 데이터 형식과 품질을 통일하고 목표 저장소에 반복 가능하게 반영하기 위해 증분 위치·변환 규칙·적재 커밋 구조가 필요함

### 쉽게 이해하기 (학습용)
- 원천 자료를 밖에서 정리한 뒤 창고에 넣거나 먼저 창고에 넣고 안에서 정리하는 두 방식임

## Ⅱ. 특징

- 원천별 변경 위치·수집 시각을 기록해 실패 구간과 재처리 범위를 식별함
- 변환 코드는 스키마·키·품질·업무 규칙과 버전을 함께 관리해 결과를 재현함
- 적재는 파티션 교체·MERGE·멱등 키로 재시도 시 중복·부분 결과를 통제함
- ETL은 정제 전 데이터의 목표 저장소 노출을 제한하고 ELT는 원천 보존과 Pushdown 연산을 활용함
- 계보·품질 결과·실행 상태를 입력 구간과 연결해 오류가 발생한 원천·단계를 추적함

### 쉽게 이해하기 (학습용)
- 처리 위치가 달라 자원 활용·원천 노출·재처리와 보안 통제 방식도 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | ETL | ELT |
|:---|:---|:---|
| 처리 순서 | 추출 후 ETL 서버·분산 처리 엔진에서 변환하고 적재 | 추출한 원천을 웨어하우스·레이크하우스에 먼저 적재하고 내부 엔진에서 변환 |
| 연산 자원 | 변환 전용 자원과 목표 적재 자원 분리 | 목표 저장소의 확장·병렬 연산 활용 |
| 원천 노출·보존 | 임시 적재 영역만 보존하며 정제 후 목표 저장소에 노출 | 목표 저장소에 원천 계층을 유지하며 접근·마스킹 통제 필요 |

> 요약: ETL은 적재 전 별도 엔진에서, ELT는 적재 후 저장소 내부에서 변환하므로 연산 위치와 원천 노출·보존 범위로 선택함.

### 쉽게 이해하기 (학습용)
- ETL은 적재 전 변환, ELT는 원천 적재 후 저장소 연산으로 변환함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원천 커넥터 | DB·파일·API를 읽고 증분 위치와 원천 메타데이터를 수집함 |
| 임시 적재 영역 | 원천 또는 중간 데이터를 재시도·대사 가능한 구간별로 저장함 |
| 변환 엔진 | 형식·키·품질·업무 규칙과 마스킹을 적용함 |
| 목표 적재기 | 추가·병합·파티션 교체로 목표 테이블을 멱등 반영함 |
| 오케스트레이터 | 의존성·스케줄·재시도·과거 구간 처리와 실행 자원을 조정함 |
| 메타데이터·품질·계보 | 스키마·규칙 버전·실행 결과·입출력 관계를 추적함 |

```text
ETL: 원천 -> 추출 -> 변환 -> 적재 -> 목표 저장소
ELT: 원천 -> 추출 -> 적재 -> 목표 저장소에서 변환 -> 제공
```

> 요약: 공통 추출·적재 요소를 사용하되 ETL은 외부 변환, ELT는 목표 저장소 내부 변환으로 실행 위치가 갈림.

### 쉽게 이해하기 (학습용)
- 원천 연결기, 임시 저장, 변환기, 목표 적재기와 실행·품질·계보 관리로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
ETL: 증분 추출 -> 임시 적재 -> 변환·품질 검사 -> 목표 커밋
ELT: 증분 추출 -> 원천 영역 커밋 -> 목표 엔진 변환 -> 정제 영역 커밋
```

1. **증분 추출**: 로그 위치·갱신 시각·파일 구간으로 원천 변경 범위를 고정함
2. **중간 커밋**: ETL은 임시 적재 영역에, ELT는 목표 저장소의 원천 영역에 입력을 보존함
3. **규칙 실행**: 스키마·키·품질·업무 변환을 선택한 연산 위치에서 수행함
4. **목표 반영**: 파티션 교체나 MERGE로 성공한 데이터 구간을 원자적으로 게시함
5. **위치 확정**: 품질·대사 결과를 기록하고 완료한 원천 위치를 다음 실행 기준으로 저장함

> 요약: 원천 구간을 고정한 뒤 ETL은 적재 전, ELT는 원천 영역 적재 후 변환하고 성공한 목표 구간과 위치를 확정함.

### 쉽게 이해하기 (학습용)
- 처리 구간을 고정하고 변환·적재 순서를 실행한 뒤 성공 위치를 확정함

## Ⅵ. 실무 사례

1. 급여 웨어하우스는 ETL에서 민감 열을 마스킹하고 적재 성공률·원천 대사 차이를 확인함
2. 로그 레이크하우스는 ELT로 원천 데이터를 보존하고 원천·정제 구간 처리 시간·재처리 완료 시간을 확인함

### 쉽게 이해하기 (학습용)
- 민감 원천과 대규모 웨어하우스에서 재처리 시간·목표 대사·원천 노출을 확인함

## Ⅶ. 결론

- ETL·ELT는 변환 위치·원천 보존·민감 데이터 노출·목표 연산 자원과 재처리 요구를 기준으로 선택해야 함
- 도구 명칭보다 데이터 상태 전이·멱등 적재·대사·보안 경계를 명확히 하고 재실행으로 검증해야 함

### 쉽게 이해하기 (학습용)
- 어느 공장에서 정리하든 같은 재료를 다시 넣어도 결과가 겹치지 않고 원본과 맞아야 함
