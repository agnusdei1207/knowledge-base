## Ⅰ. 개요
- 정의: 락을 얻을 때까지 반복 확인하는 스핀락과 대기 상태로 전환되는 뮤텍스의 비교
- 배경: 임계 구역 대기 시간이 짧은지 긴지에 따라 CPU 소모와 문맥 교환 비용이 달라짐
- 출제 의도: 바쁜 대기(Busy Waiting)와 수면 상태(Sleep State)의 비용 편익 분석 역량 평가

## Ⅱ. 구성요소
```
[ Spinlock ]            [ Mutex ]
while(lock == 1);       if(lock == 1) sleep();
lock = 1;               lock = 1;
(CPU Occupied)          (Context Switch)
```
| 구성요소 | 설명 | 비용 기준 |
| :--- | :--- | :--- |
| 스핀락 | 락 획득 시까지 CPU를 점유하며 반복 확인 | 짧은 대기와 CPU 소모 |
| 뮤텍스 | 락을 못 얻으면 대기 큐로 이동하고 CPU 반납 | 긴 대기와 문맥 교환 |
| 오버헤드 | 스핀락은 CPU 소모, 뮤텍스는 컨텍스트 스위칭 비용 | 임계 구역 길이 |
> 요약: 스핀락은 락을 반복 검사하며 CPU를 점유하고, 뮤텍스는 대기 스레드를 재우고 문맥 교환을 수행함.

## Ⅲ. 절차
```
[Lock Req] -> [Wait Method Selection] -> [CS Entry] -> [Unlock]
```
1. 스레드가 공유 자원 사용을 위해 락 획득을 시도함
2. 락 보유 시간이 문맥 교환 시간보다 짧을 것으로 예상되면 스핀락으로 반복 검사함
3. 락 보유 시간이 길거나 선점될 수 있으면 뮤텍스로 스레드를 대기 상태로 전환함
4. 락 소유자가 작업을 마치면 대기 중인 스레드를 깨우거나(Mutex) 루프 탈출 허용(Spinlock)
> 요약: 예상 대기 시간에 따라 CPU 소모와 문맥 교환 비용을 비교해 선택함.

## Ⅳ. 문제점
- 원인: 싱글 코어에서 선점 비활성 상태로 스핀하면 락 소유자의 실행 기회가 제한될 수 있음
- 원인: 뮤텍스의 컨텍스트 스위칭 비용이 임계 구역 실행 시간보다 클 경우 성능 역전 발생

## Ⅴ. 개선방안
- (단기) 임계 영역의 길이를 최소화하고 성격에 맞는 락 프리미티브 선택
- (중기) 적응형 뮤텍스(Adaptive Mutex)를 사용하여 초기에는 스핀, 이후 수면으로 전환
- (장기) 원자적 연산 비용과 락 범위를 함께 줄이는 자료구조 설계

## Ⅵ. 전망
- 멀티코어 환경에서는 미세 락(Fine-grained Lock)과 락 경합 관측이 성능 분석 기준이 됨
- 가상화 환경에서는 vCPU 선점 상태를 고려한 paravirtual spinlock 같은 기법이 활용됨

## 작성 근거(검토용)

- 스핀락과 뮤텍스는 속도 우열이 아니라 예상 대기 시간, CPU 소모, 문맥 교환 비용으로 선택해야 함
- 싱글 코어 문제는 반복 대기 단정이 아니라 선점 비활성 상태에서 락 소유자가 실행되지 못하는 조건으로 설명함
