## 미리 알고가기

- 바쁜 대기: 조건이 충족될 때까지 CPU에서 반복 검사하는 대기 방식임
- 수면 대기: 실행 주체를 대기 큐로 옮기고 CPU를 다른 작업에 배분하는 방식임
- 락 보유시간: 소유자가 락을 획득한 뒤 해제할 때까지의 시간임

## 작성 근거(검토용)

- 스핀락과 뮤텍스는 예상 대기시간·CPU 상태·문맥 전환·선점 조건·적용 영역으로 비교함
- 두 락의 대기 상태 전이가 달라 획득 실패 이후의 흐름을 각각 분리함
- 커널과 서버 런타임 사례는 스핀 시간·락 대기시간·문맥 전환 수로 검증함

## Ⅰ. 개요
- **정의/개념**: 스핀락은 락을 반복 검사하며 CPU를 점유하고, 뮤텍스는 획득 실패 시 스레드를 대기 상태로 전환하는 상호 배제 기법임
- **배경/필요성**: 락 대기시간에 따라 바쁜 대기의 CPU 비용과 수면·깨움의 문맥 전환 비용이 달라지므로 선택 기준이 필요함

## Ⅱ. 특징

- 스핀락은 대기 큐 전환 없이 원자적 연산으로 락 상태를 반복 확인함
- 뮤텍스는 획득 실패 스레드를 대기 큐로 보내고 락 해제 시 깨움함
- 스핀락은 락 보유시간이 짧고 소유자가 다른 코어에서 실행 중일 때 적용함
- 뮤텍스는 대기가 길거나 소유자가 선점될 수 있는 임계 구역에 적용함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스핀락 | 뮤텍스 |
|:---|:---|:---|
| 대기 방식 | 바쁜 대기 | 수면 대기 |
| CPU 상태 | 반복 검사로 CPU 점유 | 대기 큐 이동 후 CPU 반납 |
| 전환 비용 | 문맥 전환 없음 | 수면·깨움 문맥 전환 |
| 적합 대기시간 | 문맥 전환보다 짧은 대기 | 문맥 전환보다 긴 대기 |
| 선점 조건 | 소유자가 다른 코어에서 계속 실행 가능 | 소유자가 선점돼도 대기 가능 |
| 대표 적용 사례 | 커널의 짧은 다중코어 임계 구역 | 사용자 스레드의 장기 임계 구역 |

> 요약: 스핀락은 짧은 대기 동안 CPU를 점유하고, 뮤텍스는 긴 대기에서 스레드를 재워 CPU를 반납함.

## Ⅳ. 구성요소 및 구조
```
[ Spinlock ]            [ Mutex ]
while(lock == 1);       if(lock == 1) sleep();
lock = 1;               lock = 1;
(CPU Occupied)          (Context Switch)
```
| 구성요소 | 설명 | 비용 기준 |
| :--- | :--- | :--- |
| 원자적 락 변수 | 획득 가능 여부를 compare-and-swap 같은 연산으로 갱신함 | 소유권 판정 |
| 스핀 루프 | 락이 사용 중이면 상태를 반복 읽음 | 스핀 시간 |
| 뮤텍스 대기 큐 | 획득 실패 스레드를 재우고 순서를 관리함 | 수면·깨움 |
| 해제·깨움 경로 | 락을 해제하고 대기 스레드 또는 스핀 중인 코어에 실행 기회를 제공함 | 후속 진입 |
> 요약: 스핀락은 락을 반복 검사하며 CPU를 점유하고, 뮤텍스는 대기 스레드를 재우고 문맥 교환을 수행함.

## Ⅴ. 원리 및 절차 흐름도
```
[스핀락] 획득 시도 -> 실패 시 반복 검사 -> 성공 시 임계 구역 -> 해제
[뮤텍스] 획득 시도 -> 실패 시 대기 큐·수면 -> 깨움 후 재시도 -> 해제
```
1. **스핀락**: 원자적 획득에 실패하면 같은 코어에서 반복 검사하고 성공하면 임계 구역에 진입함
2. **뮤텍스**: 획득에 실패하면 대기 큐로 이동하고 깨움 후 락 획득을 다시 시도함
3. **해제**: 소유자가 락 상태를 해제하고 뮤텍스 대기자가 있으면 하나를 깨움함
> 요약: 예상 대기 시간에 따라 CPU 소모와 문맥 교환 비용을 비교해 선택함.

## Ⅵ. 실무 사례

1. 다중코어 커널은 짧은 인터럽트 임계 구역에 스핀락을 적용하고 평균 스핀시간과 CPU 사용량을 확인함
2. 서버 런타임은 장기 공유 상태에 뮤텍스를 적용하고 락 대기시간과 문맥 전환 수를 확인함

## Ⅶ. 결론

- 락 보유시간이 문맥 전환보다 짧고 소유자가 실행 중이면 스핀락, 그 외에는 뮤텍스를 선택함
