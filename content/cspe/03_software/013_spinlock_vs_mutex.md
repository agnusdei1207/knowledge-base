## Ⅰ. 개요
- 정의: 락을 얻을 때까지 무한 루프를 돌며 기다리는 스핀락과 잠들었다가 깨어나는 뮤텍스
- 배경: 임계 구역 대기 시간의 길이에 따라 시스템 전체 성능을 최적화하기 위한 선택의 문제
- 출제 의도: 바쁜 대기(Busy Waiting)와 수면 상태(Sleep State)의 비용 편익 분석 역량 평가

## Ⅱ. 구성요소
```
[ Spinlock ]            [ Mutex ]
while(lock == 1);       if(lock == 1) sleep();
lock = 1;               lock = 1;
(CPU Occupied)          (Context Switch)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 스핀락 | 락 획득 시까지 CPU를 점유하며 루프 수행 | 문 앞에서 서성임 |
| 뮤텍스 | 락을 못 얻으면 대기 큐로 이동하고 CPU 반납 | 의자에서 자고 있음 |
| 오버헤드 | 스핀락은 CPU 소모, 뮤텍스는 컨텍스트 스위칭 비용 | 대기 방식의 차이 |
> 요약: 스핀락은 짧은 대기에, 뮤텍스는 긴 대기에 유리함.

## Ⅲ. 절차
```
[Lock Req] -> [Wait Method Selection] -> [CS Entry] -> [Unlock]
```
1. 스레드가 공유 자원 사용을 위해 락 획득을 시도함
2. 대기 시간이 짧을 것으로 예상되면 스핀락으로 즉시 재시도 수행
3. 대기 시간이 길면 뮤텍스를 통해 프로세스 상태를 Blocked로 변경하고 스케줄링 제외
4. 락 소유자가 작업을 마치면 대기 중인 스레드를 깨우거나(Mutex) 루프 탈출 허용(Spinlock)
> 요약: 자원 점유 상태에 따라 대기 메커니즘을 달리하여 효율성을 높임.

## Ⅳ. 문제점
- 원인: 싱글 코어 환경에서 스핀락 사용 시 무한 루프로 인해 락 해제 기회 상실 가능성
- 원인: 뮤텍스의 컨텍스트 스위칭 비용이 임계 구역 실행 시간보다 클 경우 성능 역전 발생

## Ⅴ. 개선방안
- (단기) 임계 영역의 길이를 최소화하고 성격에 맞는 락 프리미티브 선택
- (중기) 적응형 뮤텍스(Adaptive Mutex)를 사용하여 초기에는 스핀, 이후 수면으로 전환
- (장기) 하드웨어 수준의 원자적 연산(Atomic Instruction) 최적화 및 락 범위 최소화 설계

## Ⅵ. 전망
- 멀티코어/매니코어 환경의 확대로 커널 내부의 미세 락(Fine-grained Lock) 제어 중요성 증대
- 가상화 및 클라우드 환경에서 하이퍼바이저가 스레드 상태를 조절하는 지능형 동기화 기술 부각
