## Ⅰ. 개요
- 정의: 하이퍼바이저 기반 하드웨어 가상화(VM)와 커널 공유 기반 프로세스 격리(Container) 기술.
- 출제 의도: 클라우드 컴퓨팅 인프라의 핵심 기술 차이점 및 활용 사례 비교 이해도 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ App A ] [ App B ]      [ App A ] [ App B ]
  [ Guest OS ] [ Guest OS ] [ Bins/Libs ] [ Bins/Libs ]
  [ Hypervisor ]            [ Container Engine ]
  [ Host OS ]               [ Host OS / Kernel ]
  [ Hardware ]              [ Hardware ]
     < VM 구조 >             < Container 구조 >

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 하이퍼바이저 | VM 생성 및 자원 할당을 담당하는 소프트웨어 계층 | 아파트 관리인 |
| 게스트 OS | VM 내부에 설치되는 독립적인 운영체제 | 입주자 전용 가구 |
| 컨테이너 엔진 | 커널 공유를 통한 컨테이너 실행 및 관리(Docker 등) | 공유 오피스 매니저 |
> 요약: VM은 HW 수준 가상화로 격리성 높음, 컨테이너는 OS 수준 가상화로 민첩성 우수함.

## Ⅲ. 절차
- ASCII 흐름도
  [이미지 생성] -> [저장소 푸시] -> [이미지 풀] -> [컨테이너 실행]
- 4단계 설명
1. 개발 환경에서 애플리케이션 및 종속성을 포함한 이미지 빌드함.
2. 빌드된 이미지를 중앙 레지스트리에 저장 및 공유함.
3. 실행 환경에서 필요 시 이미지를 로컬로 다운로드함.
4. 컨테이너 엔진이 격리된 프로세스로 앱을 즉시 실행함.
> 요약: 빌드, 공유, 배포, 실행의 경량화된 파이프라인 구현함.

## Ⅳ. 문제점
- VM: Guest OS 오버헤드로 인한 자원 낭비 및 느린 부팅 속도 발생함.
- Container: 호스트 커널 공유로 인한 보안 격리 수준이 상대적으로 취약함.

## Ⅴ. 개선방안
- VM: Unikernel 또는 MicroVM(Firecracker) 도입을 통한 오버헤드 최소화 필요함.
- Container: gVisor, Kata Containers 등 샌드박스 기술 적용으로 격리 보안 강화함.

## Ⅵ. 전망
- 인프라 복잡성 증대에 따라 VM과 컨테이너를 혼용하는 하이브리드 가상화 전략 확산됨.
- Wasm(WebAssembly)이 컨테이너의 보완재로 등장하여 서버리스 및 엣지 컴퓨팅에서 주류 기술로 부상할 것임.
- 보안과 성능의 트레이드오프 해결을 위한 하드웨어 지원 가상화(Intel VT-x 등) 최적화 지속됨.
