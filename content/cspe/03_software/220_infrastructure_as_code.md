## Ⅰ. 개요
- **정의**: 인프라 구성을 코드로 정의하여 버전 관리·자동 프로비저닝하는 관리 방식
- **배경/필요성**: 수동 콘솔 작업은 재현 불가능하고 환경 간 편차를 유발하여 운영 사고의 원인이 됨
- **비유**: 건물 설계도를 코드로 작성하면 동일 건물을 원하는 만큼 자동으로 시공하는 것

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 선언적 vs 절차적 방식 비교 | 멱등성·버전 관리·Drift 감지 | Terraform(선언적)과 Ansible(절차적) 혼용 시나리오 구분 |

> 요약: 인프라를 코드로 관리하여 재현성과 자동화를 확보하는 운영 패러다임임

## Ⅱ. 구성요소
```text
Code(HCL/YAML) --> VCS(Git) --> CI/CD Pipeline --> Cloud API --> Infra
                                     |
                               State File (현재 상태 기록)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 선언적 코드 | 원하는 최종 상태를 기술하는 템플릿(Terraform HCL 등) | 건물 설계도 |
| State File | 현재 프로비저닝된 인프라 상태를 기록하는 파일 | 시공 현황 대장 |
| Provider | 클라우드 API와 연동하여 리소스를 생성·수정·삭제하는 플러그인 | 전문 시공사 |

> 요약: 선언적 코드-상태 파일-프로바이더로 인프라 생명주기를 관리하는 구조임

## Ⅲ. 절차
```text
코드 작성 --> Plan(변경 미리보기) --> Apply(적용) --> Drift 감지
```
- 1단계: 코드 작성 — 인프라 리소스를 선언적 언어로 정의하고 VCS에 커밋
- 2단계: Plan — 현재 State와 코드를 비교하여 변경 사항을 미리 산출
- 3단계: Apply — 승인된 Plan을 실행하여 클라우드 API로 리소스 프로비저닝
- 4단계: Drift 감지 — 주기적으로 실제 인프라와 State를 비교하여 수동 변경을 탐지

> 요약: 작성-Plan-Apply-Drift 감지의 4단계로 인프라를 코드 기반 관리함

## Ⅳ. 문제점
- State 파일 충돌: 다수 운영자가 동시 작업 시 State 잠금 경합이 발생함
- 비밀정보 노출: 코드·State 내 패스워드·키가 평문으로 저장될 위험이 있음
- 대규모 Drift: 수동 콘솔 변경이 누적되면 코드와 실제 인프라 간 괴리가 확대됨

> 요약: State 충돌, 비밀정보 노출, Drift 누적이 주요 과제임

## Ⅴ. 개선방안
1. 단기: 원격 State 백엔드(S3+DynamoDB 잠금) 도입으로 동시 작업 충돌 방지
2. 중기: Vault 등 비밀관리 시스템과 연동하여 민감정보를 코드에서 분리
3. 장기: 정책 코드(OPA/Sentinel) 적용으로 Drift 발생 시 자동 교정 파이프라인 구축

> 요약: 원격 State, 비밀 분리, 정책 자동화 순으로 거버넌스를 강화함
