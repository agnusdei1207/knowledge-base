## Ⅰ. 개요
- 응용 프로그램과 데이터 사이에서 중재자 역할을 하며 데이터를 통합 관리하는 시스템임.
- 데이터의 중복성 최소화, 독립성 확보, 무결성 유지를 목적으로 함.
- 출제 의도: 데이터 모델 변화에 따른 DBMS의 발전 계보와 특징 비교 능력을 평가함.

## Ⅱ. 구성요소
- DBMS 구조
[User/App] <-> [Query Processor] <-> [Storage Manager] <-> [Database]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Query Processor | SQL 분석, 최적화 및 실행 계획 수립 | 식당의 주방장 |
| Storage Manager | 디스크 내 데이터 접근 및 버퍼 관리 | 식재료 창고 관리자 |
| Dictionary | 스키마, 제약 조건 등 메타데이터 저장 | 레시피 북 |
> 요약: 엔진(프로세서)과 저장소(매니저)가 협업하여 질의를 처리함.

## Ⅲ. 절차
- 질의 처리 흐름
[Query] -> (Parsing) -> (Optimization) -> (Execution) -> [Result]

1. 질의 파싱: SQL 문법 검사 및 구문 분석 트리 생성함.
2. 질의 최적화: 통계 정보를 활용하여 최저 비용 경로 선택함.
3. 질의 실행: 실행 엔진이 스토리지 매니저를 통해 데이터 접근함.
4. 결과 반환: 추출된 데이터를 사용자 형식에 맞춰 전송함.
> 요약: 분석, 최적화, 실행의 단계를 거쳐 최적의 결과를 도출함.

## Ⅳ. 문제점
- 고정된 스키마로 인한 유연성 부족 및 수평 확장성 한계 (Scale-out 제약).

## Ⅴ. 개선방안
- NoSQL 도입을 통한 비정형 데이터 수용 및 Sharding 기반 수평 확장 구현함.

## Ⅵ. 전망
- 클라우드 네이티브 환경에 최적화된 Serverless DBMS 및 AI 기반 자동 튜닝(AIOps) 도입 가속화.
- 자율 운영 DB(Autonomous DB)가 관리 비용 절감의 핵심 동력이 될 것임.
