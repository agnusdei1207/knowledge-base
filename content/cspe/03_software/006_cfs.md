## Ⅰ. 개요
- 정의: CFS는 실행 시간에 가중치를 반영한 vruntime을 기준으로 다음 실행 태스크를 선택하는 리눅스 스케줄러임
- 배경: 기존 O(1) 스케줄러의 휴리스틱 의존을 줄이고 인터랙티브 작업의 대기 시간을 관리할 기준이 필요함
- 출제 의도: Virtual Runtime 기반의 공정성 구현 원리와 레드-블랙 트리의 활용 이해

## Ⅱ. 구성요소
```
[ Red-Black Tree ]
      ( 15ms )  <-- Virtual Runtime (Smallest = Leftmost)
      /      \
  ( 10ms ) ( 20ms )
    /  \      /  \
  (P1) (P2) (P3) (P4)
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| Virtual Runtime | 실행 시간에 가중치(Nice)를 반영한 가상 시간 | CPU 사용량 보정값 |
| Red-Black Tree | vruntime 기준 정렬된 자가 균형 이진 탐색 트리 | 최소 vruntime 탐색 |
| Time Slice | 프로세스 가중치에 비례하여 동적으로 계산되는 시간 | 가중치별 배분량 |
> 요약: vruntime이 가장 작은 프로세스를 다음 실행 대상으로 선택함.

## Ⅲ. 절차
```
[Execution] -> [vruntime Update] -> [Tree Re-insert] -> [Pick Leftmost]
```
1. 현재 실행 중인 프로세스의 vruntime을 실행 시간에 비례하여 증가시킴
2. 타임 슬라이스 소진 또는 인터럽트 발생 시 해당 프로세스를 트리에서 제거
3. 갱신된 vruntime 값에 따라 프로세스를 RB-Tree에 재삽입(O(log N))
4. 트리의 가장 왼쪽(Leftmost) 노드, 즉 vruntime이 가장 작은 프로세스 디스패치
> 요약: vruntime이 작은 작업을 먼저 골라 CPU 사용량 편차를 줄임.

## Ⅳ. 문제점
- 원인: 실행 태스크 수가 늘면 스케줄링 주기 안의 태스크별 실행 시간이 minimum granularity까지 감소함
- 원인: nice 가중치와 wakeup 보정 설정이 워크로드와 맞지 않으면 태스크별 CPU 배분 편차가 커짐

## Ⅴ. 개선방안
- (단기) 최소 할당 시간(Minimum Granularity) 설정을 통한 잦은 스위칭 방지
- (중기) Cgroups를 활용한 그룹 단위 스케줄링으로 CPU 사용량과 격리 범위 제어
- (장기) 멀티코어 환경의 부하 분산(Load Balancing) 알고리즘 고도화 및 확장성 개선

## Ⅵ. 전망
- 클라우드 워크로드에서는 CFS 지표를 활용해 지연 시간 변동과 CPU 할당 편차를 관리함
- eBPF 기반 스케줄링 확장은 workload별 정책 실험과 관측 가능성을 높이는 방향으로 활용됨

## 작성 근거(검토용)

- CFS는 공정성을 무조건 달성한다고 쓰기보다 vruntime이 작은 작업을 선택해 CPU 사용량 편차를 줄인다고 설명해야 정확함
- Red-Black Tree는 예시가 아니라 최소 vruntime 탐색을 가능하게 하는 자료구조로 제시해야 답안 판단 축이 살아남
