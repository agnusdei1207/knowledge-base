## 미리 알고가기

- 가상 실행시간(vruntime): 실제 실행시간을 nice 가중치로 보정한 CPU 사용량임
- nice: 태스크별 CPU 배분 가중치를 결정하는 사용자 우선순위 값임
- 레드-블랙 트리: vruntime 순서로 실행 가능 태스크를 관리하는 균형 탐색 트리임

## 작성 근거(검토용)

- CFS는 vruntime 갱신·최솟값 선택·가중 CPU 배분 관계로 설명함
- 고정 시간 할당 방식과 비교해 선택 기준·우선순위 반영·실행시간·제약을 구분함
- 서버 사례는 태스크별 CPU 사용 편차와 스케줄링 지연을 직접 확인하도록 구성함

## Ⅰ. 개요
- **정의/개념**: CFS는 실제 실행시간을 nice 가중치로 보정한 vruntime이 가장 작은 태스크를 선택하는 리눅스 스케줄러임
- **배경/필요성**: 실행 가능 태스크 사이의 CPU 사용량 편차를 줄이기 위해 가중 실행시간 기반 선택 기준이 필요함

## Ⅱ. 특징

- 태스크가 실행되면 nice 가중치에 따라 vruntime이 증가함
- 실행 가능 태스크는 vruntime 순서로 레드-블랙 트리에 배치됨
- 스케줄러는 가장 작은 vruntime을 가진 태스크를 다음 대상으로 선택함
- 최소 실행시간과 깨움 보정값은 전환 빈도와 대화형 태스크 지연을 결정함

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정 시간 할당 스케줄링 | CFS |
|:---|:---|:---|
| 선택 기준 | 큐 순서·고정 시간 할당량 | 최소 vruntime |
| 우선순위 반영 | 큐·고정 우선순위 | nice 가중치로 실행시간 보정 |
| 실행시간 배분 | 동일 시간 할당량 반복 | 실행 가능 태스크의 가중치 비율 |
| 대기 관리 | 에이징·다중 큐 별도 적용 | vruntime 차이와 깨움 보정 사용 |
| 주요 제약 | 할당량별 문맥 전환 비용 | 최소 실행시간·가중치·깨움 설정 |

> 요약: 고정 시간 할당은 큐와 시간 할당량으로, CFS는 가중 vruntime으로 다음 태스크를 선택함.

## Ⅳ. 구성요소 및 구조
```
[ Red-Black Tree ]
      ( 15ms )  <-- Virtual Runtime (Smallest = Leftmost)
      /      \
  ( 10ms ) ( 20ms )
    /  \      /  \
  (P1) (P2) (P3) (P4)
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 가상 실행시간 | 실행시간을 nice 가중치로 보정함 | CPU 사용량 비교 |
| 레드-블랙 트리 | 실행 가능 태스크를 vruntime 순서로 저장함 | 최소 vruntime 탐색 |
| 목표 지연시간·최소 실행시간 | 실행 가능 태스크 수에 따라 실행 구간의 하한을 정함 | 전환 빈도 통제 |
> 요약: vruntime이 가장 작은 프로세스를 다음 실행 대상으로 선택함.

## Ⅴ. 원리 및 절차 흐름도
```
[Execution] -> [vruntime Update] -> [Tree Re-insert] -> [Pick Leftmost]
```
1. **실행시간 반영**: 현재 태스크의 실제 실행시간을 nice 가중치로 보정해 vruntime에 더함
2. **태스크 재배치**: 갱신된 vruntime 순서에 맞춰 태스크를 트리에 다시 배치함
3. **최솟값 선택**: 트리에서 vruntime이 가장 작은 실행 가능 태스크를 고름
4. **디스패치**: 선택한 태스크의 문맥을 복원해 CPU를 배분함
> 요약: vruntime이 작은 작업을 먼저 골라 CPU 사용량 편차를 줄임.

## Ⅵ. 실무 사례

1. 멀티테넌트 서버는 cgroup별 nice 가중치를 설정하고 CPU 사용 비율과 스케줄링 지연을 확인함
2. 대화형 리눅스는 최소 실행시간을 조정하고 초당 문맥 전환 수와 입력 응답시간을 확인함

## Ⅶ. 결론

- CFS는 nice 가중치와 vruntime으로 CPU 사용량을 보정하고 최소 vruntime 태스크를 선택함
