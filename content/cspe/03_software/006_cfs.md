## Ⅰ. 개요
- 정의: 리눅스 커널의 기본 스케줄러로, 모든 프로세스에게 공평하게 CPU 시간을 배분하는 기법
- 배경: 기존 O(1) 스케줄러의 복잡한 휴리스틱 해결 및 인터랙티브 작업의 응답성 강화 필요
- 출제 의도: Virtual Runtime 기반의 공정성 구현 원리와 레드-블랙 트리의 활용 이해

## Ⅱ. 구성요소
```
[ Red-Black Tree ]
      ( 15ms )  <-- Virtual Runtime (Smallest = Leftmost)
      /      \
  ( 10ms ) ( 20ms )
    /  \      /  \
  (P1) (P2) (P3) (P4)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Virtual Runtime | 실행 시간에 가중치(Nice)를 반영한 가상 시간 | 누적 점수 |
| Red-Black Tree | vruntime 기준 정렬된 자가 균형 이진 탐색 트리 | 성적순 명부 |
| Time Slice | 프로세스 가중치에 비례하여 동적으로 계산되는 시간 | 지분율 |
> 요약: vruntime이 가장 작은 프로세스를 다음 실행 대상으로 선택함.

## Ⅲ. 절차
```
[Execution] -> [vruntime Update] -> [Tree Re-insert] -> [Pick Leftmost]
```
1. 현재 실행 중인 프로세스의 vruntime을 실행 시간에 비례하여 증가시킴
2. 타임 슬라이스 소진 또는 인터럽트 발생 시 해당 프로세스를 트리에서 제거
3. 갱신된 vruntime 값에 따라 프로세스를 RB-Tree에 재삽입(O(log N))
4. 트리의 가장 왼쪽(Leftmost) 노드, 즉 vruntime이 가장 작은 프로세스 디스패치
> 요약: 정렬된 트리 구조를 활용하여 공정성을 수학적으로 보장함.

## Ⅳ. 문제점
- 원인: 프로세스 수가 급증할 경우 각 프로세스에 할당되는 타임 슬라이스가 극소화됨
- 원인: 우선순위가 매우 낮은 작업이 vruntime 정체로 인해 특정 시점에 CPU를 독점할 우려

## Ⅴ. 개선방안
- (단기) 최소 할당 시간(Minimum Granularity) 설정을 통한 잦은 스위칭 방지
- (중기) Cgroups를 활용한 그룹 단위 스케줄링으로 자원 격리 및 보호 강화
- (장기) 멀티코어 환경의 부하 분산(Load Balancing) 알고리즘 고도화 및 확장성 개선

## Ⅵ. 전망
- 클라우드 워크로드의 예측 가능성을 높이기 위해 지연 시간(Latency) 보장형 CFS 연구 활발
- eBPF를 활용하여 사용자 정의 스케줄링 정책을 동적으로 주입하는 기술이 주류가 될 것임
