## Ⅰ. 개요
- **정의**: 동일 조건에서 복수 제품의 성능을 비교 측정하여 최적 제품을 선정하는 테스트임
- **배경/필요성**: 벤더 제공 스펙만으로는 실 환경 적합성 판단 불가하므로 실측 기반 비교 필요
- **비유**: 같은 코스에서 여러 자동차를 동시에 주행시켜 연비·속도를 비교하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| BMT 절차와 평가 기준 설계 방법 | 동일 환경·동일 시나리오 통제 원칙 | 성능 테스트(313)와 BMT 목적 차이 구분 |

> 요약: 동일 조건 하 복수 제품 비교를 통해 객관적 제품 선정 근거를 확보하는 테스트임

## Ⅱ. 구성요소
```text
BMT Framework
  +-- Test Environment (동일 HW/SW 환경)
  +-- Test Scenario (업무 시나리오)
  +-- Evaluation Criteria (평가 항목/배점)
  +-- Result Report (비교 분석 보고서)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 테스트 환경 | 모든 제품에 동일한 HW·OS·네트워크 조건 제공 | 동일 트랙 조건 |
| 테스트 시나리오 | 실 업무 기반 표준 워크로드 정의 | 동일 코스·동일 주행 조건 |
| 평가 기준 | 성능·안정성·호환성 등 항목별 가중치 배점 | 채점 기준표 |
| 결과 보고서 | 제품별 정량 비교 분석 및 종합 순위 도출 | 시험 성적표 |

> 요약: 동일 환경·시나리오·평가 기준으로 제품별 정량 비교 결과를 도출함

## Ⅲ. 절차
```text
평가 기준 수립 -> 환경 구축/시나리오 작성 -> 제품별 테스트 실행 -> 결과 비교/선정
```
- 1단계: 요구사항 기반 평가 항목·배점·합격 기준 수립
- 2단계: 동일 HW·SW 환경 구축, 실 업무 기반 테스트 시나리오 작성
- 3단계: 제품별 동일 시나리오 실행 후 TPS·응답시간·자원사용률 측정(312 참조)
- 4단계: 항목별 점수 산정, 종합 비교표 작성 후 최종 제품 선정

> 요약: 기준 수립부터 비교 선정까지 4단계로 객관적 제품 비교를 수행함

## Ⅳ. 문제점
- 환경 통제 실패: 제품별 최적 설정 차이 미반영 — 공정 비교 왜곡
- 시나리오 편향: 특정 제품에 유리한 워크로드 설계 — 평가 객관성 훼손
- 단기 측정: 짧은 테스트 시간으로 내구성 미검증 — 장기 운영 적합성 판단 불가

> 요약: 환경 통제·시나리오 편향·단기 측정이 BMT 공정성과 신뢰성을 저해함

## Ⅴ. 개선방안
1. 단기: 벤더별 튜닝 기회 균등 제공 및 설정 값 공개로 환경 공정성 확보
2. 중기: 제3자(독립 기관) 시나리오 설계 및 검증으로 편향 방지
3. 장기: Soak 테스트(313 참조) 포함 장기 BMT 프레임워크 표준화

> 요약: 튜닝 공정성 → 독립 설계 → 장기 테스트 포함으로 BMT 신뢰성을 확보함

## Ⅵ. 전망
- 발전 방향: 클라우드 SaaS 제품 대상 자동화 BMT 플랫폼 등장
- 기술사적 판단: BMT는 제품 도입 의사결정의 정량적 근거로서 지속 활용될 것임
- 기술사 제언: 평가 기준의 사전 합의와 결과 재현성 확보가 BMT 신뢰의 전제 조건임
