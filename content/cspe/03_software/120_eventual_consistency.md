## 미리 알고가기

- 복제본은 같은 데이터를 여러 위치에 나눠 저장한 사본임
- 최종 일관성은 지금 바로 같지는 않아도 시간이 지나면 같은 상태로 맞춰지는 성질임
- 자신의 방금 수정한 값을 바로 다시 보는 성질은 읽은 뒤 자기 변경분을 보는 보장이라고 이해하면 됨

## Ⅰ. 개요

- **정의/개념**: 최종 일관성은 분산 시스템에서 쓰기 직후 모든 복제본이 즉시 같아지지 않아도 시간이 지나면 결국 같은 상태로 수렴하도록 운영하는 일관성 방식임
- **배경/필요성**: 여러 지역의 복제본이 모든 쓰기에 동기 합의하면 네트워크 왕복과 분할 장애가 쓰기 응답에 반영되므로, 허용 업무는 비동기 전파와 후속 수렴을 사용함

## Ⅱ. 특징

- 낮은 지연과 높은 가용성을 얻기 쉬움
- 짧은 시간 동안 오래된 값이 보일 수 있음
- 결국 같은 상태로 맞춰지려면 복제와 병합 규칙이 필요함
- 사용자 화면마다 허용 가능한 지연 범위가 다름

## Ⅲ. 종류 및 비교

| 판단 기준 | 강한 일관성 | 최종 일관성 |
|:---|:---|:---|
| 읽기 결과 | 최신 commit 확인 후 응답 | 복제 지연 동안 이전 버전 응답 가능 |
| 장애·지연 처리 | 복제 확인 실패 시 요청 거부·지연 | 연결 가능한 복제본에서 응답 후 재동기화 |
| 주의점 | 동기화 비용이 큼 | 지연 범위와 병합 규칙이 필요함 |
| 잘 맞는 업무 | 결제, 재고 | 카탈로그, 피드, 캐시 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 쓰기 수락 지점 | 어느 복제본이 먼저 변경을 받을지 정함 |
| 변경 전파 | 나머지 복제본으로 값을 퍼뜨림 |
| 지연 허용 구간 | 얼마 동안 값 차이를 허용할지 정함 |
| 충돌 해결 규칙 | 동시에 바뀐 값을 어떤 기준으로 합칠지 정함 |

```text
+---------+      +---------+      +---------+
| 사용자 요청 | ---> | 복제본 A | ---> | 복제본 B |
+---------+      +---------+      +---------+
                     |
                     v
               잠시 값 차이 발생
                     |
                     v
               시간이 지나며 수렴
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 한 노드에 먼저 기록 | --> | 다른 복제본으로 전파 | --> | 잠시 값 차이 발생 | --> | 결국 같은 상태로 수렴 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **한 노드에 먼저 기록**: 변경 요청을 우선 수락함
2. **다른 복제본으로 전파**: 변경 내용을 순차적으로 퍼뜨림
3. **잠시 값 차이 발생**: 일부 조회는 이전 값을 볼 수 있음
4. **결국 같은 상태로 수렴**: 복제가 끝나면 값이 맞춰짐

## Ⅵ. 실무 적용 및 유의점

1. 상품 카탈로그처럼 잠시 다른 값이 보여도 되는 데이터는 최종 일관성을 써도 되지만 허용 지연 시간을 먼저 정하고 데이터 지연 시간과 오래된 값 조회 건수로 범위를 점검함
2. 회원 정보 수정 직후처럼 사용자가 방금 바꾼 값을 바로 다시 봐야 하는 화면은 기본 복제 읽기만 쓰지 말고 주 노드 읽기나 세션 기반 읽기를 함께 두고 즉시 재조회 성공률과 중복 요청 건수로 보완 효과를 확인함

## Ⅶ. 결론

최종 일관성의 핵심은 불일치를 방치하는 데 있지 않고 어디까지 늦어질 수 있는지 정한 뒤 결국 같은 상태로 맞추는 운영 규칙을 갖추는 데 있음.
