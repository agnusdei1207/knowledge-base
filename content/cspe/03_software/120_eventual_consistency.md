## 미리 알고가기

- 복제본은 같은 데이터를 여러 위치에 나눠 저장한 사본임
- 최종 일관성은 복제 지연 동안 값이 다를 수 있으나 쓰기가 멈추면 같은 상태로 수렴하는 성질임
- 자신의 쓰기 읽기는 사용자가 방금 수정한 값을 다음 조회에서 확인하도록 보장하는 성질임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 최종 일관성은 비동기 전파·복제 지연·상태 수렴을 핵심 축으로 설명함
- 비교표는 강한 일관성과 최종 일관성의 읽기·장애 처리 특성을 대비함
- 분산 DB는 데이터 지연·오래된 값 조회 건수로 검증함

## Ⅰ. 개요

- **정의/개념**: 최종 일관성은 쓰기 직후 복제본 간 값 차이를 허용하되 변경 전파가 끝나면 같은 상태로 수렴하는 분산 일관성 방식임
- **배경/필요성**: 다지역 복제의 동기 합의 지연을 줄이면서 데이터 상태를 수렴시키기 위해 비동기 전파·충돌 해결·지연 허용 범위가 필요함

## Ⅱ. 특징

- 낮은 지연과 높은 가용성을 얻기 쉬움
- 짧은 시간 동안 오래된 값이 보일 수 있음
- 결국 같은 상태로 맞춰지려면 복제와 병합 규칙이 필요함
- 사용자 화면마다 허용 가능한 지연 범위가 다름

## Ⅲ. 종류 및 비교

| 판단 기준 | 강한 일관성 | 최종 일관성 |
|:---|:---|:---|
| 쓰기 확인 | 필요한 합의·복제 확인 후 성공 응답 | 한 노드에서 수락한 뒤 다른 복제본에 비동기 전파 |
| 읽기 결과 | 최신 커밋 확인 후 응답 | 복제 지연 동안 이전 버전 응답 가능 |
| 분할 시 동작 | 최신 상태를 보장할 수 없으면 요청 거부·지연 | 연결 가능한 복제본에서 응답 후 재동기화 |
| 수렴·충돌 처리 | 합의·동기 복제로 응답 전 상태 확정 | 변경 전파와 버전·병합 규칙으로 사후 수렴 |
| 운영 검증 | 커밋 지연·합의 실패율 확인 | 복제 지연·오래된 값 조회·병합 실패 건수 확인 |
| 적합 조건 | 즉시 최신 값과 원자적 판단이 필요한 결제·재고 | 한시적 이전 값을 허용하는 카탈로그·피드·캐시 |

> 요약: 강한 일관성은 최신 상태를 확인한 뒤 응답하고, 최종 일관성은 복제 지연을 허용한 뒤 상태를 수렴시킴.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 쓰기 수락 지점 | 어느 복제본이 먼저 변경을 받을지 정함 |
| 변경 전파 | 나머지 복제본으로 값을 퍼뜨림 |
| 지연 허용 구간 | 얼마 동안 값 차이를 허용할지 정함 |
| 충돌 해결 규칙 | 동시에 바뀐 값을 어떤 기준으로 합칠지 정함 |

> 요약: 쓰기 수락 지점의 변경을 다른 복제본에 전파하고 지연 허용과 충돌 해결 규칙으로 상태를 수렴시킴.

## Ⅴ. 원리 및 절차 흐름도

1. **한 노드에 먼저 기록**: 변경 요청을 우선 수락함
2. **다른 복제본으로 전파**: 변경 내용을 순차적으로 퍼뜨림
3. **잠시 값 차이 발생**: 일부 조회는 이전 값을 볼 수 있음
4. **결국 같은 상태로 수렴**: 복제가 끝나면 값이 맞춰짐

> 요약: 한 복제본에 기록한 변경을 비동기로 전파하고 일시적 값 차이를 거쳐 모든 복제본을 같은 상태로 맞춤.

## Ⅵ. 실무 사례

1. 상품 카탈로그는 비동기 복제를 적용하고 데이터 지연·오래된 값 조회 건수를 확인함
2. 회원 정보 화면은 자신의 쓰기 읽기를 보장하고 즉시 재조회 성공률·중복 요청 건수를 확인함

## Ⅶ. 결론

- 최종 일관성은 허용 가능한 복제 지연과 충돌 해결 규칙을 정해 모든 복제본을 같은 상태로 수렴시킴
