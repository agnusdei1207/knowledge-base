## Ⅰ. 개요
- **정의**: 2가지 이상 독립된 인증 요소를 결합하여 신원을 검증하는 다중 인증 방식
- **배경/필요성**: 단일 요소(비밀번호)만으로는 탈취 시 전체 계정이 노출되므로 요소 다중화가 필요함
- **비유**: 금고를 열 때 비밀번호(지식)와 열쇠(소유)를 함께 요구하는 이중 잠금 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인증 요소 분류와 조합 원리 | 지식·소유·생체 3요소의 독립성 | 같은 유형 2개(비밀번호+PIN)는 MFA가 아님 |

> 요약: 독립된 인증 요소 2가지 이상을 조합하여 단일 요소 탈취의 위험을 상쇄하는 방식임

## Ⅱ. 구성요소
```text
        +--- Knowledge (지식): 비밀번호, PIN
        |
User ---+--- Possession (소유): OTP, 보안키, 스마트카드
        |
        +--- Inherence (생체): 지문, 홍채, 안면
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Knowledge Factor | 사용자가 알고 있는 정보(비밀번호, PIN) | 금고 비밀번호 |
| Possession Factor | 사용자가 소유한 장치(OTP 토큰, 보안키) | 금고 열쇠 |
| Inherence Factor | 사용자 고유 생체 특성(지문, 홍채) | 금고 주인 지문 |
| OTP Generator | 시간·이벤트 기반 일회용 코드 생성기 | 매번 바뀌는 열쇠 번호 |
| Adaptive MFA | 위험 수준에 따라 요구 인증 요소를 동적 조정하는 정책 | 위험도별 잠금 단계 |

> 요약: 지식·소유·생체 3가지 독립 요소 중 2개 이상을 결합하여 인증 강도를 높임

## Ⅲ. 절차
```text
User -> System : ID/PW 입력 (1차: 지식)
System -> User : OTP 요청 (2차: 소유)
User -> System : OTP 입력
System          : 두 요소 모두 검증 -> 접근 허용
```
- 1단계: 사용자가 ID와 비밀번호(지식 요소)를 입력함
- 2단계: 시스템이 등록된 장치로 OTP를 전송하거나 보안키 인증을 요청함
- 3단계: 사용자가 소유 장치의 OTP 또는 생체정보(소유/생체 요소)를 제출함
- 4단계: 시스템이 모든 요소를 검증하여 인증을 완료하고 접근을 허용함

> 요약: 지식 요소 확인 후 추가 요소를 순차 검증하여 최종 인증을 완료하는 흐름임

## Ⅳ. 문제점
- 사용자 불편 증가: 인증 단계 추가로 로그인 시간과 이탈률이 증가함
- 채널 의존 취약: SMS OTP는 SIM 스와핑·중간자 공격에 노출됨
- 복구 절차 복잡: 소유 장치 분실 시 복구 프로세스가 번거롭고 지연됨

> 요약: 사용자 불편·SMS 채널 취약·장치 분실 복구가 주요 과제임

## Ⅴ. 개선방안
1. 단기: Adaptive MFA 도입으로 저위험 상황에서 인증 단계를 축소하여 불편 완화
2. 중기: SMS OTP를 FIDO 보안키·앱 기반 TOTP로 대체하여 채널 보안 강화
3. 장기: Passkey(174 참조) 기반 패스워드리스 MFA로 전환하여 복구 절차 간소화

> 요약: Adaptive 정책·FIDO 전환·패스워드리스 MFA로 편의성과 보안을 동시 확보 필요함

## Ⅵ. 전망
- 발전 방향: 행위 기반 인증(Behavioral Biometrics)이 제4 인증 요소로 부상 중임
- 기술사적 판단: 제로트러스트 환경에서 MFA는 선택이 아닌 기본 요건으로 정착함
- 기술사 제언: 인증 보증 수준(AAL) 등급별 요소 조합 정책 수립이 필요함
