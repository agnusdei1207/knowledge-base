## Ⅰ. 개요
- 데이터베이스의 상태를 변화시키는 하나의 논리적 기능을 수행하는 작업 단위임.
- 데이터 무결성을 보장하기 위해 ACID라 불리는 4가지 필수 속성을 만족해야 함.
- 출제 의도: 장애 복구 및 동시성 제어의 근간이 되는 트랜잭션 원리 이해.

## Ⅱ. 구성요소
- ACID 속성
[A] + [C] + [I] + [D] = [Integrity]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Atomicity (원자성) | All or Nothing. 모두 반영되거나 아예 안 됨 | 계좌 이체 (출금+입금) |
| Consistency (일관성) | 실행 전후 DB 상태가 규칙에 맞게 고정됨 | 마이너스 통장 잔고 제한 |
| Isolation (격리성) | 연산 중에는 다른 연산이 접근 불가함 | 화장실 1인 사용 |
| Durability (영속성) | 완료된 결과는 시스템 장애 시에도 보존됨 | 영수증 기록 보관 |
> 요약: ACID는 DB가 신뢰할 수 있는 상태를 유지하기 위한 헌법임.

## Ⅲ. 절차
- 트랜잭션 상태 변화
[Active] -> (Partially Committed) -> (Committed)
      |         |
      +-----> (Failed) -> (Aborted)

1. 활성(Active): 트랜잭션이 시작되어 실행 중인 상태임.
2. 부분 완료: 마지막 연산 실행 후 Commit 대기 중인 상태임.
3. 완료(Committed): 성공적으로 종료되어 DB에 영구 반영된 상태임.
4. 철회(Aborted): 실패하여 이전 상태로 Rollback된 상태임.
> 요약: 실행에서 완료 혹은 철회까지의 상태 전이를 엄격히 관리함.

## Ⅳ. 문제점
- 엄격한 격리성 보장 시 동시 처리 성능(Throughput) 저하 및 Deadlock 발생.

## Ⅴ. 개선방안
- 업무 성격에 따른 트랜잭션 격리 수준(Isolation Level)의 전략적 조정.

## Ⅵ. 전망
- 분산 마이크로서비스(MSA) 확산으로 Saga 패턴 등 분산 트랜잭션 기법 중요도 증대.
- 분산 원장 기술(Blockchain)과의 결합을 통한 투명한 트랜잭션 이력 관리 고도화.
