## Ⅰ. 개요
- 정의: 개발자가 서버 관리 없이 코드(함수)만 작성하여 실행하고 사용량만큼 비용을 지불하는 모델.
- 출제 의도: 클라우드 네이티브의 최종 진화 형태인 추상화 수준과 이벤트 기반 실행 구조 이해도 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Event Source ] -> [ Trigger ] -> [ FaaS (Function) ] -> [ BaaS (Backend) ]
  (S3, DB, HTTP)      (Gateway)      (Business Logic)      (DB, Auth, Log)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| FaaS | 특정 이벤트에 반응하여 실행되는 stateless 함수 단위 서비스 | 주문 시 즉석 요리 |
| BaaS | 외부 업체가 제공하는 백엔드 서비스(DB, 인증 등) API | 배달 전문 플랫폼 |
| 트리거 | 함수 실행을 유발하는 사건(파일 업로드, API 호출 등) | 벨 호출 |
> 요약: 인프라 관리 부담을 벤더가 전담(NoOps)하고 가용성/확장성을 자동 보장함.

## Ⅲ. 절차
- ASCII 흐름도
  [코드 업로드] -> [이벤트 발생] -> [컨테이너 기동] -> [함수 실행 후 폐기]
- 4단계 설명
1. 개발자는 비즈니스 로직을 담은 소스 코드를 클라우드 플랫폼에 등록함.
2. 설정된 이벤트(예: 이미지 저장)가 감지되면 실행 환경이 자동 준비됨.
3. 요청 즉시 함수가 실행되어 결과를 반환하거나 데이터를 처리함.
4. 실행 완료 후 사용된 자원은 즉시 회수되어 유휴 자원 낭비 방지함.
> 요약: 요청이 있을 때만 자원을 점유하는 On-demand 실행 방식임.

## Ⅳ. 문제점
- 콜드 스타트(Cold Start): 장시간 미사용 후 첫 호출 시 환경 구성에 따른 초기 지연 시간 발생함.
- 벤더 종속성(Lock-in): 특정 클라우드사의 독점 API 및 환경에 종속되어 이전이 어려움.

## Ⅴ. 개선방안
- Provisioned Concurrency: 자주 쓰이는 함수는 환경을 미리 유지하여 콜드 스타트 제거함.
- 오픈소스 서버리스: Knative, OpenFaaS 등 오픈소스 활용하여 멀티 클라우드 이식성 확보함.

## Ⅵ. 전망
- 엣지 컴퓨팅과의 결합(Edge Functions)을 통해 사용자 근접 위치에서 초저지연 처리 가속화됨.
- 대규모 배치 처리나 복잡한 AI 추론 워크로드로 적용 범위가 지속 확장될 것임.
- FinOps 관점에서 비용 최적화를 위한 최우선 아키텍처 선택지로 고려되며 'Green IT' 실현에 기여함.
