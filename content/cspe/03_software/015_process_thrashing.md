# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 스레싱은 **가상 메모리 환경에서 다중 프로그래밍 정도가 너무 높아져, 프로세스들이 실제 작업보다 페이지 폴트 처리(디스크 스왑)에 CPU 시간을 더 쓰며 처리량이 급락하는 병목 현상**으로, 실행에 필요한 페이지 집합(워킹셋)을 물리 메모리가 담지 못할 때 발생한다.
- **왜 필요한가**: 메모리 부족을 무시하고 프로세스를 계속 올리면 CPU 이용률이 오히려 곤두박질친다. 스레싱을 이해해야 "왜 프로세스를 늘렸는데 시스템이 더 느려지는가"를 진단하고 워킹셋·PFF로 방어할 수 있다.
- **핵심 직관**: 좁은 책상에 책을 펼쳐 공부하는 것과 같다. 책상(물리 메모리)에 필요한 책 몇 권(워킹셋)만 있으면 술술 되지만, 과목을 너무 많이 벌이면 책상이 좁아 책을 계속 꺼냈다 넣었다(스왑) 하느라 정작 공부(연산)는 못 하고 자리 정리만 반복하는 상태가 스레싱이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 답안용에 나오는 가상 메모리·스레싱 관련 표기를 비유와 함께 먼저 세운다. 맨 위가 이 주제의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 스레싱 (상위 키워드) | 페이지 폴트 처리에 시간을 다 써 처리량 급락 | 책 꺼냈다 넣기만 반복해 공부 못 함 |
| 가상 메모리 (Virtual Memory) | 물리 메모리보다 큰 주소 공간을 디스크로 확장 | 좁은 책상을 책장으로 넓혀 쓰기 |
| 페이지 (Page) | 가상 메모리를 나눈 고정 크기 블록(보통 4KB) | 책 한 권 |
| 페이지 폴트 (Page Fault) | 접근한 페이지가 물리 메모리에 없어 디스크에서 적재 | 책장에서 책을 꺼내 오는 일 |
| 스왑 (Swap) | 페이지를 메모리-디스크 간 교체 이동 | 책상과 책장 사이 책 오가기 |
| 다중 프로그래밍 정도 (MPL) | 메모리에 동시에 올린 프로세스 수 | 동시에 벌인 과목 수 |
| 워킹셋 (Working Set) | 최근 Δ 시간 동안 참조한 페이지 집합 | 지금 공부에 실제 필요한 책 몇 권 |
| 워킹셋 윈도우 (Δ) | 워킹셋을 판단하는 최근 참조 시간 범위 | "최근 10분간 편" 기준 |
| 지역성 (Locality) | 참조가 일부 페이지에 몰리는 성질 | 한 과목 볼 땐 그 책만 계속 봄 |
| PFF (Page Fault Frequency) | 페이지 폴트 발생률로 프레임 수를 조절 | 책 꺼내는 빈도로 책상 크기 조정 |
| 프레임 (Frame) | 물리 메모리를 나눈 페이지 크기 칸 | 책상 위 책 한 권 놓을 자리 |
| CPU 이용률 (Utilization) | CPU가 실제 연산에 쓰인 시간 비율 | 실제 공부한 시간 비율 |

## 깊이 이해
- **배경·문제의식**: OS는 CPU 이용률이 낮으면 "프로세스를 더 올리면 되겠지" 하고 다중 프로그래밍 정도(MPL)를 높인다. 그런데 메모리가 부족하면 각 프로세스가 워킹셋조차 못 채워 페이지 폴트가 폭증하고, 폴트 처리(디스크 I/O, 수 ms) 동안 프로세스가 블록되어 CPU가 놀게 된다. OS는 이를 또 "이용률 낮음"으로 오판해 프로세스를 더 올리는 악순환에 빠진다. 이 지점이 스레싱이다.
- **작동 원리(어떻게+왜)**:
  - **정상 구간**: MPL을 늘리면 CPU 이용률이 함께 오른다. 프로세스가 I/O로 블록될 때 다른 프로세스가 CPU를 쓰기 때문이다.
  - **임계점 통과**: 각 프로세스에 할당되는 프레임이 워킹셋 크기 아래로 떨어지는 순간, 폴트율이 급격히 상승한다. 참조하는 페이지가 자꾸 메모리에 없어 디스크를 오간다.
  - **붕괴(스레싱)**: 거의 모든 프로세스가 페이지 폴트 대기 상태가 되어 CPU 이용률이 절벽처럼 떨어진다. 시스템은 스왑 I/O만 하고 실제 연산은 거의 못 한다.
  - **방어(왜 워킹셋·PFF인가)**: 워킹셋 모델은 각 프로세스가 최근 Δ 동안 쓴 페이지 집합만큼 프레임을 보장하고, 총 워킹셋 합이 물리 메모리를 넘으면 프로세스를 잠시 내려(suspend) MPL을 낮춘다. PFF는 폴트율을 직접 감시해 상한 초과 시 프레임을 더 주고, 하한 미만이면 회수해 적정 지점을 유지한다.
- **비유**: 좁은 책상(메모리)에서 여러 과목을 동시에 벌이면(높은 MPL), 책 놓을 자리가 모자라 매번 책장(디스크)에서 꺼냈다 넣었다만 반복하며 정작 문제는 못 푼다. 과목 수를 줄여 지금 필요한 책(워킹셋)이 다 책상에 오르게 하면 공부가 다시 술술 진행된다.
- **구체 예시**: 물리 메모리 8GB 서버에서 각 4GB 워킹셋을 가진 프로세스 2개까지는 정상이지만, 3개째를 올리면 총 12GB 요구로 프레임이 부족해져 폴트율이 급증하고 스왑 사용률이 90%를 넘으며 CPU는 5%로 놀고 응답이 수십 초로 늘어난다. 리눅스에서 `vmstat`의 `si/so`(스왑 in/out) 급증과 CPU `wa`(I/O 대기) 폭증이 스레싱 신호다.
- **흔한 오해·주의점**: (1) **스레싱은 CPU가 느려서가 아니라 메모리 부족·과다 MPL 때문이다** — CPU를 올려도 해결되지 않고 메모리 증설·MPL 하향이 근본 해법이다. (2) **페이지 폴트 자체는 정상** — 요구 페이징에서 폴트는 늘 있으며, 문제는 폴트율이 유효 접근 시간을 지배할 만큼 폭증할 때다. (3) 지역성이 없는(랜덤 접근) 워크로드는 워킹셋이 커서 스레싱에 더 취약하다.

## 연결 개념
- 워킹셋·PFF 모델(018 참조) — 스레싱을 예방·조절하는 프레임 할당 기법의 상세
- 다중 프로그래밍·다중 처리(019 참조) — MPL이 CPU 이용률·스레싱에 미치는 관계
- 페이지 교체 알고리즘(017 참조) — 폴트 시 어떤 페이지를 내보낼지에 따른 폴트율 영향

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 스레싱은 다중 프로그래밍 정도 과다로 프레임이 워킹셋에 못 미쳐, 페이지 폴트 처리에 CPU를 소진하며 처리량이 급락하는 현상임.
> 2. **가치**: MPL과 CPU 이용률의 관계에 임계점이 있음을 인식해, 워킹셋·PFF로 적정 MPL을 유지해야 시스템 붕괴를 막음.
> 3. **판단 포인트**: 근본 원인은 메모리 부족·과다 MPL이므로 CPU 증설이 아니라 메모리 증설·프로세스 suspend·워킹셋 보장이 해법임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스레싱 발생 원리 | MPL 과다 -> 폴트율 급증 -> CPU 이용률 급락 | 원인을 CPU 성능 부족으로 단정 |
| MPL·이용률 임계 관계 | 정상 상승 후 임계점서 붕괴 | 페이지 폴트 자체를 이상으로 오해 |
| 예방·해소 기법 | 워킹셋 모델·PFF·프로세스 suspend | 워킹셋·PFF 조절 메커니즘 누락 |

> 요약: 스레싱을 MPL-이용률 임계 관계로 설명하고, 워킹셋·PFF로 적정 MPL을 유지하는 예방책을 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 프레임 부족으로 페이지 폴트 처리가 실제 연산을 압도해 처리량이 급락하는 현상임
- 배경: OS가 낮은 CPU 이용률을 MPL 상향으로 오판·대응해 폴트 악순환에 빠짐
- 필요성: MPL과 이용률의 임계 관계를 알아야 워킹셋·PFF로 붕괴를 예방하고 성능을 지킬 수 있음

## Ⅱ. 구조 및 구성요소

선형 구조도 (MPL 증가에 따른 CPU 이용률 곡선):

    MPL(동시 프로세스 수) 증가
      -> 정상 구간: CPU 이용률 함께 상승(I/O 중첩 효과)
      -> 임계점: 프레임 < 워킹셋 -> 페이지 폴트율 급증
      -> 스레싱 구간: 대부분 폴트 대기 -> CPU 이용률 급락
    방어: 워킹셋 보장 / PFF 조절 / 프로세스 suspend

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 다중 프로그래밍 정도(MPL) | 동시 적재 프로세스 수 | 임계점 넘으면 스레싱 유발 |
| 워킹셋 | 최근 Δ 참조 페이지 집합 | 프레임이 이보다 적으면 폴트 급증 |
| 페이지 폴트율 | 단위 시간 폴트 발생 빈도 | 스레싱의 직접 지표 |
| PFF 제어기 | 폴트율 상·하한으로 프레임 조절 | 상한 초과 시 프레임 증가 |
| 프로세스 suspend | MPL 하향 위해 일부 프로세스 스왑아웃 | 스레싱 해소의 직접 수단 |

> 요약: MPL 상승은 임계점까지 이용률을 올리나, 프레임이 워킹셋을 밑돌면 폴트 급증으로 이용률이 붕괴하며 워킹셋·PFF·suspend로 방어함.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도 (스레싱 악순환):

    CPU 이용률 낮음 관측 -> OS가 MPL 상향(프로세스 추가)
      -> 프로세스별 프레임 감소 -> 워킹셋 미충족 -> 페이지 폴트 급증
      -> 프로세스들 디스크 I/O 대기로 블록 -> CPU 이용률 더 하락
      -> OS가 또 MPL 상향 (악순환) -> 스레싱

- 1단계 [오판 유발]: OS가 낮은 CPU 이용률을 보고 처리량을 높이려 프로세스를 추가 적재함
- 2단계 [프레임 부족]: 프로세스당 할당 프레임이 워킹셋 크기 아래로 떨어져 필요한 페이지가 메모리에 없어짐
- 3단계 [폴트 폭증]: 프로세스들이 페이지 폴트로 디스크 스왑을 반복하며 대부분 I/O 대기 상태가 됨
- 4단계 [붕괴·악순환]: CPU가 놀아 이용률이 더 떨어지고, OS가 이를 또 오판해 MPL을 높이며 스레싱이 심화됨

> 요약: 낮은 이용률 오판이 MPL 상향을 부르고, 프레임 부족이 폴트 폭증·CPU 놀림을 낳아 악순환으로 스레싱이 심화됨.

## Ⅳ. 특징

- 임계점 존재: MPL 증가 시 이용률이 오르다 특정 지점에서 급격히 붕괴하는 비선형 곡선을 보임
- 악순환성: 낮은 이용률을 MPL 상향으로 대응하는 OS의 오판이 스레싱을 스스로 악화시킴
- 원인의 국소성: CPU 성능이 아니라 메모리 부족·과다 MPL이 근본 원인이라 CPU 증설로 해소되지 않음
- 지역성 의존: 참조 지역성이 강하면 워킹셋이 작아 방어가 쉽고, 랜덤 접근은 취약함
- 관측 신호 명확: 스왑 in/out과 I/O 대기 시간 급증으로 조기 진단이 가능함

## Ⅴ. 심화 비교 및 적용 판단

시스템 상태를 정상 구간과 스레싱 구간(과다 MPL) 축으로 대조함(워킹셋·PFF 상세는 018 참조).

| 구분 | 정상 구간 | 스레싱 구간(과다 MPL) |
|:---|:---|:---|
| MPL 대비 이용률 | 함께 상승 | 급격히 하락 |
| 프레임 vs 워킹셋 | 프레임 ≥ 워킹셋 충족 | 프레임 < 워킹셋 미충족 |
| 페이지 폴트율 | 낮고 안정 | 폭증 |
| 지배 작업 | 실제 연산 | 디스크 스왑 I/O |
| CPU 이용률 | 높음 | 매우 낮음(놀고 대기) |
| 대응 | MPL 소폭 상향 가능 | 프로세스 suspend·메모리 증설 |

> 요약: 프레임이 워킹셋을 충족하면 정상 상승 구간, 밑돌면 폴트 폭증·이용률 붕괴의 스레싱 구간이며 후자는 MPL 하향이 필요함.

**리스크·대응:**
- 스레싱 붕괴 — 과다 MPL로 프레임 < 워킹셋 — 프로세스 suspend·스왑아웃으로 MPL 즉시 하향
- 워킹셋 오산정 — Δ 윈도우 부적절로 프레임 과소·과다 — 워크로드 지역성에 맞춰 Δ 튜닝
- 반복 재발 — 근본 메모리 부족 방치 — 물리 메모리 증설·PFF 상하한 기반 자동 프레임 조절

**점검 지표:**
- 성능: 페이지 폴트율(목표 상한 이하), 유효 메모리 접근 시간(EAT)
- 운영: 스왑 in/out 비율(si/so), CPU I/O 대기 시간(wa%)

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 워킹셋 기반 적정 MPL 유지: 프로세스별 워킹셋 합이 물리 메모리를 넘지 않게 스케줄러가 적재 수를 제한
2. PFF 자동 조절: 페이지 폴트율 상한 초과 시 프레임 추가, 하한 미만 시 회수해 프레임을 동적으로 균형 유지
3. 관측 기반 방어: `vmstat`의 si/so·wa 지표를 모니터링해 스레싱 조짐 시 프로세스 suspend·메모리 증설을 자동 트리거

**결론:**
- 기술사 판단: 스왑·I/O 대기가 급증하면 MPL을 낮춰 워킹셋을 보장하고, 재발 시 CPU가 아닌 물리 메모리 증설로 대응함
- 향후 방향: 컨테이너 환경에서 cgroup 메모리 제한·워킹셋 추정 기반 오토스케일링과 NVMe 스왑·메모리 압축(zram)으로 스레싱 임계를 완화함
