# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 페이지 폴트(Page Fault)가 빈번하게 발생하여, CPU가 실제 일을 하는 시간보다 **페이지를 교체하는 데 더 많은 시간을 소비**하는 상태.
- **핵심 직관**: 시험 공부를 하는데, 책을 한 장 넘길 때마다 앞의 내용을 다 까먹어서 다시 찾아보느라 진도를 하나도 못 나가는 상황. (공부 시간 < 책장 넘기는 시간)
- **발생 경로**: 다중 프로그래밍 정도(MPD)가 너무 높으면 -> 프로세스당 할당된 페이지 프레임 수가 부족해짐 -> 페이지 폴트 급증 -> CPU 이용률 급락 -> OS는 CPU가 노는 줄 알고 프로세스를 더 추가함 -> 악순환 반복.

## 깊이 이해
- **원인 (Over-allocation)**: 물리 메모리보다 훨씬 많은 자원을 프로세스들에게 할당했을 때 발생. 각 프로세스가 실행에 필요한 최소한의 페이지(Working Set)조차 가지지 못하면 스레싱이 시작됨.
- **CPU 이용률 곡선 (Thrashing Point)**: 다중 프로그래밍 정도를 높이면 CPU 이용률이 비례해서 올라가다가, 어느 임계점(Knee Point)을 넘어서면 갑자기 수직 하락함. 이 지점이 스레싱의 시작.
- **해결책의 철학**:
    - **예방**: 프로세스당 최소 프레임 수 보장.
    - **조절**: 페이지 폴트 빈도(PFF)를 모니터링하여 너무 높으면 프로세스를 중단(Swap-out)시키고, 너무 낮으면 프레임을 회수함.

## 연결 개념
- **Virtual Memory (016)**: 스레싱이 발생하는 무대.
- **Working Set (018)**: 스레싱을 막기 위해 프로세스가 필요로 하는 '최소 집합'.
- **Page Fault (018)**: 스레싱의 직접적인 원인이 되는 이벤트.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 부족한 물리 메모리 자원에 비해 과도한 **다중 프로그래밍 정도(MPD)**로 인해 페이지 교체 오버헤드가 시스템 성능을 압도하는 현상임.
> 2. **기술적 핵심**: CPU 이용률의 급격한 하락을 유발하는 **Knee Point**를 조기에 감지하고, **Working Set** 및 **PFF(Page Fault Frequency)** 기반의 자원 재배치가 필수적임.
> 3. **가치**: 한정된 메모리 자원 하에서 시스템의 안정성과 처리량(Throughput)을 최대로 유지하기 위한 부하 제어(Load Control)의 핵심 지표임.

## Ⅰ. 시스템 성능의 절벽, 프로세스 스레싱(Thrashing)의 개요
- **정의**: 페이지 부재(Page Fault)가 과도하게 발생하여 프로세스 수행 시간보다 페이지 교체 시간이 더 커지는 성능 저하 상태.
- **현상**: CPU 이용률 급감, 디스크 I/$O(Paging)$ 급증, 시스템 응답 중단.

## Ⅱ. 스레싱의 발생 메커니즘 및 CPU 이용률 곡선

### 1. 발생 메커니즘 (악순환의 고리)
1. MPD(다중 프로그래밍 정도) 증가 -> 2. 프로세스별 가용 프레임 감소 -> 3. 페이지 부재 빈도 증가 -> 4. CPU 이용률 저하 -> 5. OS 스케줄러의 착각(MPD 추가 증가) -> 6. 스레싱 심화.

### 2. 성능 곡선 (ASCII Diagram)
```text
CPU 이용률 (%)
  ^
  |      (Knee Point)
  |        / \
  |       /   \
  |      /     \ (스레싱 발생 영역)
  |     /       \
  |____/_________\__________> MPD (다중 프로그래밍 정도)
```

## Ⅲ. 스레싱의 원인 분석 및 판단 지표

- **원인**:
    - **부족한 물리 메모리**: 절대적인 RAM 용량 부족.
    - **잘못된 페이지 교체 정책**: Global Replacement 사용 시 특정 프로세스의 폭주가 전체 시스템에 영향.
    - **높은 MPD**: 운영체제의 부적절한 부하 제어.
- **판단 지표**:
    - **Page Fault Rate**: 초당 페이지 부재 횟수.
    - **CPU Utilization**: CPU 사용량의 비정상적 하락.
    - **Disk I/O Wait**: 페이징 작업을 위한 디스크 대기 시간 급증.

## Ⅳ. 스레싱 해결 및 방지 전략 (Working Set & PFF)

### 1. Working Set Model (Locality 기반)
- **개념**: 특정 시점에 프로세스가 원활하게 실행되기 위해 참조하는 페이지들의 집합.
- **전략**: `$\sum Working Set > 물리 메모리` 이면 프로세스 중 하나를 종료(Swap-out)하여 남은 프로세스들에게 필요한 프레임을 몰아줌.

### 2. PFF (Page Fault Frequency) 조절
- **개념**: 페이지 부재율의 상한(Upper Bound)과 하한(Lower Bound)을 설정.
- **동작**: 
    - 상한 돌파 시: 해당 프로세스에 프레임 추가 할당.
    - 하한 미달 시: 프레임 회수.

## Ⅴ. 기술적 심화: 지역성(Locality)과 스레싱의 관계
- **시간 지역성 (Temporal Locality)**: 한 번 참조된 주소는 곧 다시 참조됨.
- **공간 지역성 (Spatial Locality)**: 참조된 주소 근처의 주소들이 곧 참조됨.
- **분석**: 스레싱은 프로세스의 현재 지역성 크기보다 적은 프레임이 할당되었을 때 발생함.

## Ⅵ. 기술사 관점의 결론 및 제언
- 스레싱 방지는 단순 메모리 증설보다 **'시스템 부하 제어(Admission Control)'** 능력이 중요함.
- **실무 제언**: 현대의 가상화 및 컨테이너 환경에서는 **Memory Limit(cgroups)** 설정을 통해 특정 컨테이너의 메모리 누수나 폭주가 노드 전체의 스레싱을 유발하지 않도록 격리(Isolation) 정책을 반드시 적용해야 함.
