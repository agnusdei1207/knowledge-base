## Ⅰ. 개요
- 정의: 발견된 결함의 발생부터 조치 완료까지 전 과정을 기록하고 관리하는 체계
- 배경: 결함 누락 방지, 조치 이력 보존 및 품질 통계 확보를 통한 프로세스 개선 필요
- 출제 의도: 결함 생명주기(Life Cycle) 이해 및 관리 도구(DTS) 활용 역량 측정

## Ⅱ. 구성요소
- 구조도
  [New] -> [Open] -> [Assigned] -> [Resolved] -> [Closed]
             ^                      |              |
             +--------[Reopen]------+--------------+

- 구성요소 표
| 항목 | 설명 | 비유 |
| :--- | :--- | :--- |
| 심각도(Severity) | 결함이 시스템에 미치는 영향도 | 환자의 위중함 |
| 우선순위(Priority) | 결함을 언제 수정해야 하는지 결정 | 응급실 진료 순서 |
| 결함 보고서 | 결함 발생 경로, 환경, 재현 방법 기술 | 진료 기록지 |
> 요약: 결함의 상태 변화를 실시간으로 추적하여 투명한 품질 관리 실현

## Ⅲ. 절차
- 흐름도
  결함 발견 -> 등록 -> 할당/수정 -> 확인 테스팅 -> 종료
- 4단계 설명
1. 등록: 테스터가 결함의 상세 내용과 재현 경로를 시스템에 기록
2. 할당/수정: 관리자가 개발자에게 할당하고, 개발자는 원인 분석 후 코드 수정
3. 확인 테스팅: 수정된 코드가 결함을 해결했는지 재검증 수행
4. 종료: 결함 해결이 확인되면 상태를 Closed로 변경하고 통계에 반영
> 요약: 체계적 추적을 통해 결함 수정의 누락을 방지하고 재발 방지 대책 수립

## Ⅳ. 문제점
- 결함 재현 경로 설명 부족으로 개발자와 테스터 간의 커뮤니케이션 비용 증대
- 우선순위 산정 기준의 모호성으로 인해 핵심 결함 방치 및 일정 지연 발생

## Ⅴ. 개선방안
- 화면 녹화, 로그 자동 첨부 등 표준화된 결함 보고 템플릿 강제화
- 비즈니스 영향도 기반의 객관적 우선순위 산정 매트릭스 도입 및 합의

## Ⅵ. 전망
- 인공지능 기반의 유사 결함 자동 추천 및 조치 방법 가이드 제공 기능 확산
- CSF: 결함 데이터를 분석하여 개발 프로세스의 근본 원인(Root Cause) 제거
