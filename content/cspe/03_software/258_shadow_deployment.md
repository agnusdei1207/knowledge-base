# 📖 【암기용】 개념 완전 이해

> 목적: 섀도 배포를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 섀도 배포는 실제 요청을 신규 모델에도 복제해 실행하되 사용자 응답은 기존 모델 결과만 반환하는 검증 방식이다.
- **왜 필요한가**: 신규 모델이 실제 트래픽에서 어떤 지연, 오류, 예측 분포를 보이는지 사용자 영향 없이 확인할 수 있다.
- **핵심 직관**: 신규 모델을 뒤에서 몰래 예행연습시키고 결과는 기록만 하며 실제 고객에게는 기존 답을 제공하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 오프라인 테스트 데이터는 운영 트래픽의 분포, 요청 크기, 피크 부하를 반영하지 못할 수 있다. 신규 모델을 바로 노출하면 예측 오류가 사용자에게 전달된다.
- **작동 원리**: 라우터가 요청을 기존 모델과 신규 모델에 동시에 보낸다. 기존 모델 응답만 사용자에게 반환하고 신규 모델의 예측, 지연, 오류는 로그로 비교한다.
- **비유**: 신입 상담원이 실제 상담을 옆에서 동시에 답안 작성해 보지만 고객에게는 숙련 상담원의 답변만 전달하는 훈련과 같다.
- **구체 예시**: 사기탐지 v2를 7일간 섀도 실행해 v1과 점수 차이, p95 80ms, 오류율 0.05% 이하를 확인한 뒤 카나리로 전환한다.
- **흔한 오해·주의점**: 섀도 배포는 사용자 반응을 측정할 수 없다. 클릭률이나 구매율 같은 행동 KPI는 A/B 또는 카나리에서 검증해야 한다.

## 연결 개념
- 카나리 배포: 섀도 검증 후 일부 사용자 노출
- A/B 테스트: 사용자 행동 기반 효과 검증
- 모델 모니터링: 섀도 지표 수집과 비교

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 섀도 배포 답안은 실제 트래픽 복제, 사용자 미노출, 로그 비교, 부하 비용을 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 섀도 배포는 운영 요청을 신규 모델에도 복제해 실행하지만 사용자에게는 기존 모델 응답만 반환하는 무노출 검증 방식이다.
> 2. **가치**: 실제 트래픽 기반 지연, 오류, 예측 분포를 사용자 영향 없이 측정한다.
> 3. **판단 포인트**: 사용자 반응 KPI는 측정할 수 없으므로 섀도 후 카나리 또는 A/B로 이어지는 단계 설계가 필요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 배포 검증 방식 이해 | 요청 복제, 응답 미노출, 결과 비교 | 카나리와 동일시 |
| 리스크 통제 확인 | 사용자 영향 0, 지연·오류 측정 | 업무 KPI 검증 가능하다고 단정 |
| 운영 비용 판단 | 병렬 추론 비용, 로그 저장, 개인정보 | 부하 증가와 마스킹 누락 |

> 요약: 섀도 배포는 노출 전 운영 적합성 검증이며 효과 검증은 후속 실험이 필요하다.

---

## Ⅰ. 개요 및 필요성

- 개요: 섀도 배포는 신규 모델 무노출 운영 검증 방식이다.
- 배경: 실제 요청을 신규 모델에도 복제하되 사용자는 기존 모델 결과만 받는다.
- 필요성: 운영 데이터 기반 지연, 오류, 예측 분포를 확인해 사용자 노출 전 리스크를 검증해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Client Request -> Request Mirror -> Baseline Model -> User Response
                              / Shadow Model -> Compare Log -> Metrics
```

| 구성요소 | 역할 | 통제 기준 |
|:---|:---|:---|
| Request Mirror | 운영 요청을 신규 모델로 복제 | 동기/비동기 복제 |
| Baseline Model | 실제 사용자 응답 생성 | 기존 Production |
| Shadow Model | 신규 모델 무노출 실행 | 결과 저장만 수행 |
| Compare Log | 예측 차이, 지연, 오류 비교 | score diff, p95, 5xx |

> 요약: 섀도 구조는 실제 응답 경로와 신규 모델 검증 경로를 분리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
모델 후보 준비 -> 요청 복제 설정 -> 기존 응답 반환 -> 신규 결과 저장 -> 차이 분석 -> 카나리 전환 판단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 신규 모델을 별도 엔드포인트에 배치 | 레지스트리 버전 확인 |
| 2 | 운영 요청을 비동기 복제 | 원응답 지연 영향 0ms 목표 |
| 3 | 신규 모델 결과와 지표 저장 | p95, 오류율, score diff |
| 4 | 통계 리포트 후 노출 여부 판단 | 7일 이상 피크 포함 |

> 요약: 섀도 배포는 실제 요청으로 신규 모델을 검증하되 사용자 응답 경로를 변경하지 않는다.

---

## Ⅳ. 특징

| 구분 | 카나리 배포 | 섀도 배포 | 판단 포인트 |
|:---|:---|:---|:---|
| 사용자 노출 | 일부 사용자 노출 | 사용자 미노출 | 사전 검증 목적 |
| 측정 지표 | 지연, 오류, 행동 KPI | 지연, 오류, 예측 차이 | 행동 변화 측정 불가 |
| 위험 | 일부 영향 발생 | 직접 영향 없음 | 병렬 비용 발생 |

> 요약: 섀도 배포는 사용자 영향 없이 운영 부하와 예측 차이를 검증하지만 행동 KPI는 확인하지 못한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 섀도 배포 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 오프라인 테스트 | 실제 요청 복제 | 운영 분포 확인 필요 |
| 비용/성능 | 추가 추론 없음 | 병렬 추론 비용 발생 | GPU·CPU 여유 필요 |
| 운영/위험 | 노출 후 문제 발견 | 노출 전 오류 탐지 | 고객 영향 제한 |

> 요약: 실제 트래픽 적합성은 필요하지만 사용자 노출이 부담되는 모델은 섀도 배포가 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 원서비스 지연 | 동기 복제로 응답 경로 영향 | 비동기 mirror, timeout | baseline latency delta |
| 비용 증가 | 두 모델 동시 추론 | 샘플링, 피크 시간 제한 | shadow cost |
| 개인정보 로그 | 요청 원문 저장 | 마스킹, 토큰화, 보존 기간 | PII 검출 0건 |

> 요약: 섀도 리스크는 원서비스 지연, 병렬 비용, 개인정보 로그이며 비동기 처리와 마스킹으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연 영향 | 기존 응답 p95 변화 5ms 이하 | APM 비교 |
| 신규 모델 품질 | score diff 허용 범위 내 | 비교 리포트 |
| 운영 오류 | shadow 5xx 0.1% 이하 | Gateway log |

> 요약: 섀도 성공 여부는 기존 응답 영향, 신규 결과 차이, 오류율로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Envoy, Istio, API Gateway의 traffic mirroring으로 요청을 비동기 복제하고 원응답 경로 timeout을 분리함
2. 신규 모델의 예측값, 지연, 오류, model version을 로그로 저장하고 PII는 마스킹 후 30일 보존함
3. 7일 이상 섀도 실행 후 p95 100ms, 5xx 0.1% 이하, score diff 허용 범위 통과 시 카나리로 전환함

**결론 (2줄):**
- 기술사 판단: 사용자 영향이 큰 모델은 섀도 배포로 운영 적합성을 먼저 확인하고, 행동 KPI는 카나리·A/B에서 검증함
- 향후 방향: 섀도 배포는 자동 비교 리포트와 정책 기반 승격을 통해 MLOps 배포 게이트로 정착됨
