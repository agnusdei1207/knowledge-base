## 미리 알고가기

- DevSecOps: 개발(Development), 보안(Security), 운영(Operations)을 유기적으로 연계하여 소프트웨어 생명주기 전반에 보안을 내재화하는 실천법임
- SAST(Static Application Security Testing): 소스 코드를 실행하지 않고 구문 분석 등을 통해 보안 취약점과 코딩 규칙 위반을 찾아내는 정적 분석 기술임
- SCA(Software Composition Analysis): 프로젝트에서 참조하는 오픈소스 라이브러리의 의존성 관계를 매핑하고 알려진 취약점(CVE) 유무를 분석하는 기술임
- DAST(Dynamic Application Security Testing): 애플리케이션을 실행 상태로 둔 채 외부 입력값 주입 등을 통해 런타임 취약점을 진단하는 동적 분석 기술임
- 쉬프트 레프트(Shift-Left): 개발 생명주기의 후반부(우측)에 수행하던 보안 검사를 초기 단계(좌측, 즉 개발 단계)로 전진 배치해 결함 제거 비용을 낮추는 철학임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 개발 생명주기 전체에 보안을 내재화하는 쉬프트 레프트 사상과 주요 분석 도구(SAST, SCA)를 통해 후행 보안 점검 대비의 효율성을 입증하고자 함.
- 절 구성·배치·전개 흐름 이유: Ⅰ절에서 정의와 배경 필요성을 밝히고, Ⅱ절에서 보안의 조기 배치 등 특징을 설명함. Ⅲ절에서 후행 보안 점검과 DevSecOps의 구체적 차이를 검사 시점, 제어 메커니즘, 구조적 한계 3가지 비교축으로 요약함. Ⅳ절과 Ⅴ절에서 보안 도구 및 정책의 결합 관계를 보여주는 구조와 절차를 정렬함. Ⅵ절과 Ⅶ절에서 금융권 등의 자동 통제 사례와 공학적 개선 방향을 결론으로 도출함.
- 문장별 5회 전수 검수 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정했음을 병기함.

## Ⅰ. 개요

- **정의/개념**: DevSecOps는 개발 및 배포 파이프라인의 모든 단계에 보안 검사, 정책 집행, 취약점 조치 프로세스를 자동화하여 소프트웨어 안전성을 확보하는 배포·운영 관리 방식임
- **배경/필요성**: 개발이 완료된 출시 직전에 실시하는 펜테스트나 취약점 진단은 수정 범위를 과도하게 넓혀 제품 출시 일정을 지연시키므로 개발 초기 단계의 즉각적인 보안 피드백이 필요함

### 쉽게 이해하기 (학습용)
- 건물을 다 짓고 준공 검사 때 벽을 허무는 대신, 기둥을 세우고 벽돌을 쌓을 때마다 안전 기준에 맞는지 바로 검사하며 건물을 짓는 것과 같습니다.

## Ⅱ. 특징

- 취약점 식별 단계를 코딩 및 빌드 단계로 전진(Shift-Left)시켜 잠재적 결함 수정 비용을 대폭 절감함
- 파이프라인 내에 정적 분석 및 보안 정책 검사기를 내장하여 보안 위반 시 빌드를 자동 차단함
- 보안 분석 도구의 오탐(False Positive) 비율이 높을 경우 파이프라인 우회 또는 릴리스 지연이 발생할 수 있음
- 발견된 취약점의 위험도 점수(예: CVSS v3)에 따라 자동 티켓팅을 수행하고 조치 기한을 규정함

### 쉽게 이해하기 (학습용)
- 음식점에서 음식이 손님 테이블에 나가기 직전에 상했는지 검사하는 대신, 재료를 손질할 때와 끓일 때 각각 전용 측정기로 자동 체크해 불량품을 바로 버리는 것과 같습니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 후행 보안 점검 | DevSecOps |
|:---|:---|:---|
| 검사 시점 | 개발 및 빌드가 최종 완료된 배포 직전 단계 | 소스 커밋, 빌드, 스테이징, 실운영 단계 전체 |
| 취약점 제어 | 진단 보고서 발행 후 수동 결함 수정 요청 | 파이프라인 내 정책 위반 시 자동 빌드·배포 차단 |
| 리스크 영향 | 늦은 취약점 식별로 인한 아키텍처 재설계 비용 발생 | 실시간 오탐 선별을 위한 화이트리스트 정책 유지 관리 부담 |

> 요약: 후행 점검은 배포 직전 통보되어 대형 수정을 유발하지만, DevSecOps는 파이프라인 내 자동화된 게이트로 취약점을 조기 차단함.

### 쉽게 이해하기 (학습용)
- 수동 검사는 수능 시험이 끝난 뒤에 가채점하여 불합격을 확인하는 것이라면, DevSecOps는 매 주말 모의고사를 보며 오답 노트를 바로 작성하는 것입니다.

## Ⅳ. 설계 요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 정적 보안 검사(SAST) | 소스 코드 수준에서 취약 패턴 및 안전하지 않은 API 사용을 검출하는 보안 게이트 |
| 소프트웨어 조성 분석(SCA) | 사용된 오픈소스 라이브러리의 취약점을 CVE 데이터베이스와 비교·식별하는 모듈 |
| 암호화 키/비밀값 스캐너 | 소스 코드 및 설정 파일에 하드코딩된 API 토큰 및 개인키 노출을 자동 탐지하는 컴포넌트 |
| 정책 코드화(IaC/Compliance) | 배포 적격성 기준과 보안 정책을 OPA(Open Policy Agent) 등으로 정의해 자동 통제하는 모듈 |

> 요약: 소스 취약점(SAST), 오픈소스 라이브러리(SCA), 정책(OPA) 검출 엔진이 CI/CD의 통합 게이트 역할을 함.

### 쉽게 이해하기 (학습용)
- 설계 도면 검사기, 불량 자재 판별기, 유출 방지 경보기, 안전 규정 채점기로 이루어진 일체형 자동 보안 검문소입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[코드 커밋] → [SAST/SCA 검사] → [비밀값 노출 스캔] → [정책 판정 및 승인] → [배포 및 DAST 검사]
                                                      ├─ 통과 -> 자동 배포
                                                      └─ 차단 -> 개발 환류
```

1. **코드 커밋 및 SCA/SAST 검사**: 소스 코드가 리포지토리에 푸시되면 정적 취약점 분석 및 오픈소스 의존성 취약점을 실시간 분석함
2. **비밀값 노출 스캔**: 환경 설정 파일이나 소스 코드 내에 API 키 및 인증서가 평문으로 포함되었는지 검출함
3. **정책 판정 및 승인**: 정의된 보안 수준을 충족하면 다음 단계로 넘어가고, 고위험군 취약점 탐지 시 배포를 자동 차단하고 개발자 이슈를 자동 생성함
4. **배포 및 DAST 검사**: 스테이징 환경에 배포 후 외부 입력 공격 패턴을 주입하여 동적 취약점을 런타임 진단함

> 요약: 코드 커밋 시 SAST/SCA와 비밀값 스캔을 수행하고 정책 충족 시 배포하며, 런타임에 DAST 검사를 추가 수행함.

### 쉽게 이해하기 (학습용)
- 밀가루에 쇳가루가 없는지 스캔(SAST)하고, 방부제 기준을 검사(SCA)한 후, 안전 요건을 통과하면 기계에 넣고 돌린 뒤 맛을 확인(DAST)하는 제조 공정입니다.

## Ⅵ. 실무 사례

1. 핀테크 결제 시스템 개발 시 CI 파이프라인에 SonarQube와 Snyk를 적용해 소스 코드의 OWASP Top 10 취약점을 $95\%$ 이상 자동 탐지함.
2. 클라우드 배포 단계에서 ArgoCD에 정책 코드화 도구인 OPA를 결합해 승인되지 않은 포트 개방 설정을 배포 전 단계에서 자동 격리함.

### 쉽게 이해하기 (학습용)
- 모바일 뱅킹 앱을 배포하기 전에 해킹에 취약한 코드가 있는지 로봇이 검사해서, 기준 미달이면 앱 스토어 배포 버튼을 자동으로 비활성화하는 실무 사례입니다.

## Ⅶ. 결론

- DevSecOps는 보안을 파이프라인의 필수 구성 요소로 통합함으로써 소프트웨어 안전 진단 주기를 대폭 단축하고 릴리스 위험을 완화함.
- 개발 속도 저하를 막기 위해 보안 검사의 탐지 규칙을 정밀하게 다듬어 오탐율을 $5\%$ 미만으로 유지하고 개발자의 보안 인식 교육을 병행해야 함.

### 쉽게 이해하기 (학습용)
- 보안 검사를 기계적으로 자동화하여 속도와 안전을 모두 챙기되, 기계의 오작동(오탐)을 상시 튜닝해 개발 생산성을 지켜야 한다는 뜻입니다.
