## 미리 알고가기

- DevSecOps는 보안을 개발과 배포 흐름 안에 통합하는 접근임
- SAST와 SCA와 secrets scanning과 policy as code가 자주 쓰임
- 보안은 마지막 승인 단계가 아니라 전체 파이프라인의 내장 조건이 되어야 함

## Ⅰ. 개요

- **정의/개념**: DevSecOps는 개발과 운영 자동화 흐름에 보안 점검과 정책 집행과 취약점 대응을 내장해, 보안을 별도 후행 단계가 아니라 지속적 전달 과정의 일부로 만드는 실천 체계임
- **배경/필요성**: 배포 속도가 빨라질수록 배포 직전이나 운영 단계에서만 보안을 점검하면 취약점 수정 비용이 커지고 릴리스 지연이 발생하므로, 초기부터 자동화된 보안 통제가 필요함

## Ⅱ. 특징

- 보안 검사를 개발 초반과 파이프라인 단계에 분산 배치함
- 정책 위반을 자동 차단해 배포 품질 기준을 높임
- 과도한 경고와 느린 스캔은 개발자 우회를 유발할 수 있음
- 도구 도입보다 취약점 우선순위화와 처리 책임 모델이 더 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 후행 보안 점검 | DevSecOps |
|:---|:---|:---|
| 시점 | 개발 후반/배포 직전 | 개발부터 운영까지 지속 |
| 장점 | 초기 도입 단순 | 수정 비용과 배포 지연 감소 |
| 한계 | 늦은 발견과 병목 | 도구와 정책 설계 필요 |
| 적합 환경 | 저빈도 배포 | 빠른 배포 조직 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Security Scan Stage | SAST와 SCA와 secrets scan이 코드와 의존성 위험을 조기에 드러냄 |
| Policy as Code | 배포 허용 기준을 코드로 정의해 예외 없는 자동 집행을 가능하게 함 |
| Vulnerability Triage | 모든 경고를 같은 수준으로 다루지 않고 위험도와 노출면 기준으로 우선순위를 정함 |
| Runtime Feedback | 운영 중 탐지된 보안 이벤트를 다시 개발 흐름으로 돌려 개선을 지속함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 코드/의존성 검사 | --> | 정책 판정      | --> | 배포/운영 모니터링 | --> | 취약점 개선      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **코드와 의존성 검사**: 정적 분석과 라이브러리 검사를 수행함
2. **정책 판정**: 위험도와 정책 기준에 따라 통과 여부를 결정함
3. **배포 및 운영 모니터링**: 배포 후 런타임 보안 신호를 관찰함
4. **취약점 개선**: 결과를 backlog와 수정 작업으로 연결함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 경고가 과도하거나 정확도가 낮으면 개발자가 보안 도구를 신뢰하지 않고 우회할 수 있음
   - 해결방안: false positive를 줄이고 우선순위를 조정하며 alert precision과 developer bypass rate로 검증함
2. 문제: 정책이 과도하게 엄격하면 배포 병목이 생기고 예외 처리만 늘어날 수 있음
   - 해결방안: 위험 기반 게이트를 운영하고 gate block rate와 security defect escape rate로 검증함
3. 문제: 보안 이벤트가 운영에서 발견돼도 개발 흐름과 연결되지 않으면 같은 취약점이 반복될 수 있음
   - 해결방안: runtime feedback 연계를 구축하고 remediation lead time과 recurrence vulnerability count로 검증함

## Ⅶ. 적용 사례

- 금융 서비스 CI 파이프라인에서는 DevSecOps를 적용하고 확인 지표는 gate block rate와 security defect escape rate임
- 오픈소스 의존성 많은 플랫폼에서는 SCA를 운영하고 확인 지표는 remediation lead time과 alert precision임
- 운영 보안 이벤트 연동 체계에서는 개발 backlog까지 연결하고 확인 지표는 developer bypass rate와 recurrence vulnerability count임

## Ⅷ. 결론

DevSecOps의 핵심은 보안 도구를 더 넣는 데 있지 않고 빠른 배포 흐름 안에서 보안 결함을 더 이르게 더 작게 더 자주 처리하게 만드는 데 있음.
