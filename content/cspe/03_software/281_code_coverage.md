## Ⅰ. 개요
- **정의**: 테스트가 소스코드의 어느 범위까지 실행했는지 측정하는 지표
- **배경/필요성**: 테스트가 충분한지 객관적으로 판단할 정량 기준이 필요함
- **비유**: 시험 범위 중 실제로 공부한 페이지 비율과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 커버리지 유형별 차이 이해 | 구문·분기·조건·MC/DC 구분 | 높은 커버리지가 무결함을 보장하지 않음을 명시 |

> 요약: 테스트 충분성을 정량 측정하는 코드 실행 비율 지표임

## Ⅱ. 구성요소
```text
Source Code --> Instrumentation --> Test Execution --> Coverage Report
                                        |
                                        v
                                  Hit/Miss Data
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 구문 커버리지 | 실행된 문장 수 / 전체 문장 수 비율 | 모든 방 방문 여부 |
| 분기 커버리지 | 참·거짓 분기 각각 실행 여부 측정 | 갈림길 양쪽 모두 통과 |
| 조건 커버리지 | 개별 조건식의 참·거짓 평가 여부 측정 | 스위치 각각 ON/OFF 확인 |
| MC/DC | 각 조건이 독립적으로 결과에 영향을 주는지 확인 | 각 버튼이 단독으로 결과 변경 가능 확인 |

> 요약: 구문→분기→조건→MC/DC 순으로 엄격도가 증가하는 측정 체계임

## Ⅲ. 절차
```text
대상 선정 --> 계측 삽입 --> 테스트 수행 --> 리포트 분석
```
- 1단계: 커버리지 측정 대상 모듈과 목표 기준값 선정
- 2단계: 소스코드에 계측(Instrumentation) 코드 자동 삽입
- 3단계: 테스트 스위트 실행 후 실행 경로 데이터 수집
- 4단계: 미도달 구간 식별 및 테스트 케이스 보완 수행

> 요약: 계측 삽입 후 테스트 실행·분석으로 미도달 구간을 보완하는 절차임

## Ⅳ. 문제점
- 도달 불가 코드: 방어 코드·예외 핸들러 등 정상 경로로 실행 불가 — 커버리지 수치 왜곡 발생
- 의미 없는 수치 추구: 100% 달성 자체가 목적화 — 품질과 무관한 테스트 증가
- 계측 오버헤드: 계측 코드 삽입으로 실행 시간 증가 — 대규모 시스템에서 측정 비용 과다

> 요약: 수치 왜곡·목적 전도·계측 비용이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 도달 불가 코드 태깅 후 커버리지 산정 시 제외 처리
2. 중기: 커버리지와 결함 검출률 상관 분석 기반 목표값 설정
3. 장기: 샘플링 기반 경량 계측 기법 도입으로 운영 환경 측정 지원

> 요약: 제외 처리·목표 합리화·경량 계측으로 실효성 확보 필요

## Ⅵ. 전망
- 발전 방향: CI/CD 파이프라인 내 자동 커버리지 게이트 통합 확대
- 기술사적 판단: MC/DC 수준 커버리지가 안전 필수 소프트웨어 표준으로 정착 중임
- 기술사 제언: 커버리지 수치와 결함 밀도를 함께 관리하는 복합 품질 체계 수립 필요
