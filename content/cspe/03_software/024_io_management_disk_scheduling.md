# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: CPU에 비해 속도가 현저히 느린 입출력(I/O) 장치의 병목 현상을 줄이기 위해, 요청된 I/O 작업들의 실행 순서를 최적화하는 운영체제의 핵심 기능이다.
- **왜 필요한가**: 수많은 I/O 요청이 들어올 때 들어온 순서대로만 처리하면 디스크 헤드가 좌우로 낭비하며 움직이게 되어 전체 시스템 성능이 크게 저하되기 때문에 필요하다.
- **핵심 직관**: 엘리베이터가 1층, 10층, 2층, 9층을 순서대로 누른다고 그 순서대로 움직이지 않고, 올라가는 길에 있는 층을 다 태우고 내려가는 길에 다 태우는 것(SCAN)과 같은 원리다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 탐색 시간 (Seek Time) | 디스크 헤드가 원하는 트랙(실린더)으로 이동하는 데 걸리는 시간 | 레코드판 바늘을 원하는 노래 위치로 옮기는 시간 |
| 회전 지연 (Rotational Latency) | 트랙 내에서 원하는 섹터가 헤드 아래로 회전하여 다가올 때까지 대기하는 시간 | 노래 위치에 바늘을 올렸는데 시작 부분이 올 때까지 레코드판이 도는 시간 |
| 블록 드라이버 / 캐릭터 드라이버 | 일정 크기(Block) 단위로 I/O하는 디스크 드라이버와 1바이트 문자(Character) 단위로 I/O하는 마우스/키보드 드라이버 | 화물 트럭(블록) vs 오토바이 퀵배송(캐릭터) |

## 깊이 이해
- **배경·문제의식**: CPU 속도는 나날이 빨라지지만, 하드 디스크(HDD)의 탐색 시간은 물리적 기계 팔(Head)의 이동에 의존하므로 발전 속도가 더디다. I/O 장치가 시스템 전체의 병목을 유발한다.
- **작동 원리 (디스크 스케줄링)**:
  - **FCFS**: 들어온 순서대로 처리. (공평하지만 헤드 이동 거리가 길어 비효율적)
  - **SSTF (Shortest Seek Time First)**: 현재 헤드 위치에서 가장 가까운 요청부터 처리. (바깥쪽이나 안쪽 끝 트랙의 요청이 영원히 처리되지 않는 '기아(Starvation)' 발생)
  - **SCAN (엘리베이터 알고리즘)**: 헤드가 맨 안쪽부터 바깥쪽까지 스윕(Sweep)하며 가는 길목의 모든 요청 처리 후 다시 반대 방향으로 스윕. (기아 해결, 가장 보편적)
  - **C-SCAN (Circular SCAN)**: SCAN과 같으나, 한 방향으로만 처리하고 끝에 도달하면 반대 끝으로 빠르게 돌아간 후 다시 같은 방향으로 처리. (응답 시간 편차 최소화)
- **흔한 오해·주의점**: 현대의 SSD는 물리적으로 움직이는 헤드가 없으므로, 헤드 이동 거리를 줄이려는 복잡한 탐색 알고리즘(SCAN 등)이 불필요하다. 대신 웨어 레벨링(Wear Leveling)이나 FTL 같은 내부 I/O 관리가 더 중요하다.

## 연결 개념
- 인터럽트, DMA(Direct Memory Access), 엘리베이터 알고리즘, 버퍼 캐시

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CPU(나노초)와 I/O 장치(밀리초) 간의 극심한 속도 차이를 완충하기 위해 헤드 이동 거리를 최소화하는 순서 최적화 알고리즘.
> 2. **가치**: 전체 I/O 처리량(Throughput) 향상 및 특정 요청의 무한 대기(Starvation) 방지를 통한 응답 시간 형평성 보장.
> 3. **판단 포인트**: HDD 환경에서는 헤드 이동을 줄이는 SCAN/C-SCAN이 핵심이나, SSD 환경에서는 FCFS나 NOOP 스케줄러로 전환하는 것이 올바른 아키텍처 판단이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 디스크 I/O 병목 원인과 최적화 스케줄링 기법의 진화 과정 이해 | Seek Time, SSTF의 기아(Starvation) 현상, SCAN(엘리베이터) 메커니즘 | 최신 SSD 매체의 특성을 간과하고 기계적 스케줄링만 맹신하는 답변 지양 |

> 요약: FCFS → SSTF(기아) → SCAN(방향성) → C-SCAN(형평성)으로 발전하는 탐색 시간 단축 과정을 명확히 대조한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 디스크 액세스 타임 중 가장 큰 비중을 차지하는 탐색 시간(Seek Time)을 최소화하기 위해 I/O 대기 큐의 처리 순서를 재배열하는 기법.
- 배경: 기계식 부품(Actuator Arm)을 사용하는 HDD 특성상, 무작위 I/O 요청을 순서대로 처리하면 극심한 병목 현상 발생.
- 필요성: 시스템 전체 처리량(Throughput) 극대화 및 특정 I/O 요청의 기아 상태(Starvation)를 방지하기 위해 필수적임.

---

## Ⅱ. 구조 및 구성요소

```text
[애플리케이션] -> I/O 요청 큐 -> [OS I/O 스케줄러] -> [디바이스 드라이버] -> 컨트롤러 -> 디스크 장치
                                     |
                                     +-> SCAN / SSTF 등 알고리즘 적용 (순서 재배치)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| I/O 요청 큐 | 각 프로세스에서 발생한 디스크 섹터/블록 읽기·쓰기 요청을 대기시킴 | 블록 번호와 섹터 정보 포함 |
| OS I/O 스케줄러 | 대기 중인 요청을 분석하여 물리적 헤드 이동 거리가 최소화되도록 정렬 | 엘리베이터 알고리즘 적용 |
| I/O 컨트롤러 | 스케줄러가 지시한 순서대로 실제 디바이스에 전기적 제어 신호 전달 | DMA 방식을 통해 CPU 개입 최소화 |

> 요약: 스케줄러는 I/O 큐의 요청을 단순히 전달하지 않고 알고리즘 기반으로 재정렬하여 컨트롤러에 전달한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
큐 삽입 -> 최단 탐색 검사 -> [기아 방지 스윕 수행] -> 디스크 헤드 이동 -> I/O 완료 인터럽트
```

- 1단계 [큐 삽입]: 사용자 프로세스의 `read()`/`write()` 시스템 콜에 의해 목표 실린더(트랙) 번호가 큐에 등록.
- 2단계 [스케줄링 평가]: 헤드의 현재 위치와 진행 방향(SCAN의 경우)을 기준으로 큐 내 모든 요청의 거리를 계산.
- 3단계 [순서 확정 및 이동]: 선택된 알고리즘(예: SCAN)에 따라 진행 방향에 있는 가장 가까운 실린더로 디스크 헤드를 물리적으로 이동.
- 4단계 [완료 및 인터럽트]: 데이터를 버퍼로 전송 완료 후 CPU에 인터럽트를 발생시켜 I/O 완료를 통지.

> 요약: 스케줄링은 현재 위치와 진행 방향을 기준으로 최적의 다음 목적지를 실시간 계산하여 기계적 움직임을 통제한다.

---

## Ⅳ. 특징

- 순차 처리의 한계 (FCFS): 구현은 가장 단순하지만, 디스크 양끝을 오가는 요청이 반복될 경우 응답 시간이 기하급수적으로 증가함.
- 최단 거리의 함정 (SSTF): 처리량은 매우 높으나, 헤드 위치와 멀리 떨어진 외곽 트랙의 요청은 영구히 처리되지 못하는 기아 현상이 발생함.
- 양방향 스윕 (SCAN): 엘리베이터처럼 한 방향으로 끝까지 진행하며 모든 요청을 처리한 뒤 역방향으로 전환하여, 처리량과 기아 방지를 동시에 달성함.
- 응답 시간 편차 최소화 (C-SCAN): 양방향 SCAN은 중간 트랙과 양끝 트랙 간의 응답 시간 편차가 크므로, 단방향 스윕 후 반대편 끝으로 즉시 회귀하여 편차를 줄임.

> 요약: 단순 거리 최적화(SSTF)의 기아 문제를 방향성 제어(SCAN)와 회귀(C-SCAN)를 통해 공평성과 성능의 최적점으로 진화시켰다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SSTF | SCAN | C-SCAN | 선택 기준 |
|:---|:---|:---|:---|:---|
| 알고리즘 기준 | 현재 위치 최단 거리 | 진행 방향 최단 거리 | 단방향 최단 거리 + 회귀 | 공평성(기아 방지) 요건 |
| 기아 현상 | 발생 (외곽 트랙) | 없음 | 없음 | 배치 처리 vs 실시간 트랜잭션 |
| 응답 시간 편차 | 매우 큼 | 큼 (중앙 트랙 유리) | 매우 작음 (모두 균등) | SLA 및 응답 일관성 중요도 |

> 요약: 최고의 처리량이 필요하되 기아가 무관한 환경은 SSTF, 응답 시간의 균등성이 중요한 멀티테넌트 환경은 C-SCAN을 채택한다.

**리스크·대응:**
- SSD 매체 오적용: 탐색 시간이 없는 SSD에 SCAN 알고리즘 적용 시 CPU 오버헤드만 발생 → NOOP(단순 FIFO) 또는 Deadline 스케줄러로 변경 (지표: I/O 큐 대기 시간)
- 특정 I/O 독점: 백업 작업 등 대량의 I/O가 다른 실시간 I/O를 차단 → CFQ (Completely Fair Queuing) 적용으로 프로세스별 I/O 대역폭 공평 할당 (지표: I/O 응답 지연율)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터베이스 HDD 서버 최적화: 대용량 데이터 웨어하우스(DW) 등 순차 I/O 비중이 높고 백그라운드 배치가 많은 환경에서는 C-SCAN 기반의 Deadline 스케줄러를 적용하여 일관된 성능을 확보.
2. 엔터프라이즈 SSD 스토리지 튜닝: NVMe SSD 환경에서는 Linux I/O 스케줄러를 멀티 큐(Multi-Queue) 기반의 `mq-deadline` 또는 `kyber`로 설정하여 병렬 I/O 성능을 극대화.
3. 멀티테넌시 클라우드 환경 제어: 다수의 컨테이너나 VM이 경합하는 호스트에서는 cgroups-v2를 활용해 컨테이너별 I/O 제한(Limit)과 가중치(Weight)를 부여하여 노이즈 네이버(Noisy Neighbor) 차단.

**결론 (2줄):**
- 기술사 판단: 현대 시스템 성능의 병목은 CPU가 아닌 I/O에서 발생하므로, 저장 매체의 기계적 특성(HDD vs SSD)을 정확히 식별하여 스케줄러를 튜닝하는 것이 아키텍트의 핵심 역량임.
- 향후 방향: 하드웨어 기반 스케줄링에서 벗어나, eBPF를 활용해 애플리케이션의 워크로드 특성을 동적으로 인지하여 커널단 I/O 처리 순서를 실시간 변경하는 지능형 스케줄링으로 진화할 것임.
