## 미리 알고가기

- I/O 관리는 운영체제가 장치 요청을 큐잉하고 배분하고 완료 처리하는 기능임
- 디스크 스케줄링은 저장장치 요청 순서를 조정해 지연과 처리량을 개선하는 정책임
- HDD와 SSD는 병목 특성이 달라 같은 스케줄링이 항상 유효하지 않음

## 작성 근거(검토용)

- FCFS·SCAN·Deadline·멀티큐를 요청 기준·필요 상태·얻는 결과·제약·매체로 비교함
- 요청 수집·병합·선택·장치 제출·완료를 I/O의 실제 제어 흐름으로 유지함
- HDD와 NVMe 사례를 분리해 탐색 거리와 큐 대기라는 고유 지표를 확인함

## Ⅰ. 개요

- **정의/개념**: I/O 관리와 디스크 스케줄링은 운영체제가 입출력 요청을 큐에 모으고 장치 특성에 따라 처리 순서를 정해 처리량·응답시간·공정성을 관리하는 기능임
- **배경/필요성**: 저장장치의 탐색·병렬 큐 특성과 요청 대기 상한을 반영하기 위해 I/O 요청 선택 기준이 필요함

## Ⅱ. 특징

- 장치 큐의 요청 순서·우선순위·병합 방식이 탐색 거리와 대기 시간을 결정함
- HDD는 헤드 탐색거리, SSD는 병렬 큐 깊이·큐 경합을 기준으로 요청 배치를 조정함
- I/O 관리는 장치 효율뿐 아니라 응답 시간 공정성까지 고려해야 함
- 멀티큐와 비동기 I/O는 CPU별 제출 큐와 장치 완료 큐를 통해 요청을 병렬 전달함

## Ⅲ. 종류 및 비교

| 판단 기준 | FCFS | SCAN·C-SCAN | Deadline | 멀티큐 |
|:---|:---|:---|:---|:---|
| 요청 선택 | 도착 순서 | 헤드 이동 방향·실린더 위치 | 만료시간·읽기/쓰기 큐 | CPU·하드웨어 큐별 요청 |
| 필요 상태 | 도착 큐 | 현재 헤드 위치·방향 | 요청 만료시각 | 큐별 깊이·장치 태그 |
| 얻는 결과 | 순서 보존 | HDD 탐색 이동 감소 | 요청 대기 상한 통제 | SSD 병렬 채널 활용 |
| 주요 제약 | 긴 탐색 요청 가능 | SSD에서 위치 기준 효과 없음 | 만료시간·큐 가중치 조정 | 큐별 경합·CPU 친화도 |
| 적합 매체 | 기준 정책 | HDD | HDD·SSD 지연 관리 | NVMe·다중 큐 SSD |

> 요약: FCFS는 도착 순서, SCAN은 헤드 위치, Deadline은 만료시간, 멀티큐는 CPU·장치 큐로 요청을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| I/O 요청 큐 | 프로세스·파일 시스템의 읽기·쓰기 요청을 보관함 |
| I/O 스케줄러 | 매체 특성과 정책 기준으로 요청을 병합·재배열함 |
| 장치 드라이버 | 선택한 요청을 장치 명령과 DMA 버퍼로 변환함 |
| 완료 경로 | 완료 인터럽트를 처리하고 요청 프로세스를 깨움함 |

> 요약: 요청 큐와 스케줄러가 순서를 정하고 드라이버·완료 경로가 장치 실행과 응답을 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요청 수집      | --> | 큐 정렬/우선화 | --> | 장치 제출      | --> | 완료 처리      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요청 수집**: 프로세스와 파일 시스템이 읽기나 쓰기 요청을 생성함
2. **병합·선택**: 스케줄러가 인접 요청을 병합하고 정책 기준으로 다음 요청을 고름
3. **장치 제출**: 드라이버가 장치 큐에 요청을 내려 실제 I/O를 실행함
4. **완료 처리**: 완료 인터럽트를 받아 프로세스에 결과를 전달함

## Ⅵ. 실무 사례

1. HDD 백업 서버는 SCAN으로 요청을 정렬하고 평균 탐색거리와 p99 I/O 지연을 확인함
2. NVMe 서버는 CPU별 멀티큐와 큐 상한을 설정하고 큐 경합률과 p99 I/O 지연을 확인함

## Ⅶ. 결론

- I/O 스케줄링은 저장장치의 탐색·병렬 큐 특성과 요청 대기 상한에 따라 정책을 선택함
