# 📖 【암기용】 개념 완전 이해

## 한눈에
- **I/O 관리**: CPU와 주변장치(디스크, 키보드 등) 사이의 데이터 전송을 제어하고 최적화하는 커널 기능.
- **디스크 스케줄링**: 하드디스크(HDD)의 헤드가 데이터를 읽기 위해 움직이는 경로를 최적화하여 **탐색 시간(Seek Time)을 최소화**하는 기법.
- **핵심 직관**: 아파트 배달원(디스크 헤드). 1층 갔다가 10층 갔다가 다시 2층 가는 대신, 동선을 짜서 올라가는 길에 1, 2층 들르고 내려오는 길에 처리하는 것(SCAN 알고리즘).
- **왜 중요한가**: CPU는 빛의 속도로 일하는데 디스크는 거북이처럼 움직임. 이 차이를 줄이는 것이 시스템 전체 성능의 핵심.

## 깊이 이해
- **I/O 제어 방식**:
    - **Polling**: CPU가 계속 "다 됐니?" 물어봄. (CPU 낭비 심함)
    - **Interrupt**: 장치가 완료되면 CPU를 툭 침. (효율적)
    - **DMA (Direct Memory Access)**: CPU 대신 DMA 컨트롤러가 메모리로 데이터를 직접 옮김. (CPU는 큰 그림만 그림)
- **주요 스케줄링 알고리즘**:
    - **FCFS**: 온 순서대로. (동선 낭비 심함)
    - **SSTF (Shortest Seek Time First)**: 현재 위치에서 제일 가까운 곳부터. (기아 현상 발생 가능)
    - **SCAN (엘리베이터)**: 한 방향으로 끝까지 가면서 처리하고 반대로 옴.
    - **C-SCAN**: 한 방향으로만 처리하고 끝에 도달하면 처음으로 점프. (응답 시간이 더 균일함)

## 연결 개념
- **File System (022)**: 데이터를 어디에 둘지 정하고, 스케줄링은 그걸 어떻게 읽을지 정함.
- **SSD vs HDD**: SSD는 물리적인 헤드가 없어서 스케줄링 알고리즘이 훨씬 단순(주로 FIFO)하거나 불필요함.
- **Double Buffering**: I/O가 진행되는 동안 다음 작업을 미리 준비하여 대기 시간을 줄이는 기법.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: CPU와 기계적 장치(HDD) 간의 거대한 속도 차이를 극복하기 위해 제어 방식(DMA)과 접근 경로(Scheduling)를 최적화하는 기술임.
> 2. **기술적 핵심**: HDD 환경에서는 헤드 이동 거리 최소화(**Seek Time 최적화**)가 핵심이며, SSD 환경에서는 병렬 처리와 수명 관리(Wear Leveling)가 중요함.
> 3. **판단**: 응답성(Response)이 중요하면 C-SCAN을, 전체 처리량(Throughput)이 중요하면 SSTF나 SCAN을 고려함.

## Ⅰ. 시스템 병목의 해소, I/O 관리 및 디스크 스케줄링 개요
- **I/O 관리**: 컴퓨터 시스템과 주변 장치 간의 데이터 교환을 제어하여 시스템 효율성을 높이는 기법.
- **디스크 스케줄링**: 디스크 I/O 요청 큐에 있는 작업들의 처리 순서를 결정하여 탐색 시간(Seek Time)을 단축하는 기법.

## Ⅱ. 효율적 데이터 전송을 위한 I/O 제어 방식 비교

| 제어 방식 | 원리 | 장점 | 단점 |
|:---:|:---|:---|:---|
| **Programmed I/O** | CPU가 상태 비트를 계속 체크 (Polling) | 구현 간단 | CPU 자원 낭비 극심 |
| **Interrupt-driven** | I/O 완료 시 인터럽트 발생 | CPU 효율적 사용 | 데이터 전송마다 CPU 개입 |
| **DMA** | 전용 컨트롤러가 메모리-장치 직접 전송 | **CPU 부하 최소화** | 초기 설정 오버헤드 |
| **I/O Channel** | 독립된 I/O 전용 프로세서 사용 | 대규모 시스템 최적 | 하드웨어 비용 발생 |

## Ⅲ. 디스크 스케줄링 알고리즘 상세 분석 (HDD 중심)

### 1. 주요 알고리즘 비교
| 알고리즘 | 특징 | 장점 | 단점 |
|:---:|:---|:---|:---|
| **FCFS** | 요청이 온 순서대로 처리 | 공평함, 구현 용이 | 탐색 거리 최대화 위험 |
| **SSTF** | 현재 헤드에서 가장 가까운 요청 처리 | 처리량 극대화 | **기아(Starvation) 현상** |
| **SCAN** | 한 방향 끝까지 이동 후 반대 방향 이동 | SSTF 단점 보완 (공평) | 양 끝단 대기 시간 증가 |
| **C-SCAN** | 한 방향으로만 처리, 끝 도달 시 점프 | **균등한 응답 시간 보장** | 이동 거리 다소 증가 |
| **LOOK / C-LOOK** | 요청이 있는 범위까지만 이동 (SCAN 개선) | 불필요한 끝단 이동 제거 | 구현 복잡도 |

### 2. 알고리즘 선택의 지표
- **Seek Time**: 헤드가 해당 트랙으로 이동하는 시간 (전체 I/O의 80% 차지).
- **Rotational Latency**: 섹터가 헤드 밑으로 올 때까지 기다리는 시간.

## Ⅳ. 현대적 변화: SSD와 I/O 스케줄링

- **물리적 차이**: SSD는 기계적 헤드가 없는 **반도체 기반**으로, 탐색 시간(Seek Time)이 거의 0에 수렴함.
- **알고리즘 변화**:
    - 복잡한 SCAN 알고리즘의 실익이 없음.
    - 주로 **FIFO(No-op)**나 데이터 무결성을 보장하는 간단한 큐잉 방식 사용.
    - **NCQ (Native Command Queuing)**: 장치 차원에서 요청 순서를 최적화하여 병렬 처리 극대화.

## Ⅴ. I/O 성능 향상을 위한 소프트웨어적 기법

1. **Buffering**: 전송 속도 차이를 완충하기 위해 임시 저장소(Buffer) 활용 (Double/Circular Buffering).
2. **Caching**: 자주 쓰는 데이터를 메모리에 상주시켜 디스크 접근 자체를 회피 (Page Cache).
3. **Spooling**: 고속 CPU와 저속 장치 사이의 작업을 디스크에 임시 저장하여 독립적으로 처리 (인쇄 작업 등).

## Ⅵ. 기술사 관점의 결론 및 제언
- 디스크 스케줄링은 하드웨어의 물리적 특성(HDD vs SSD)에 따라 최적화 전략이 완전히 달라짐.
- **실무 제언**: 가상화나 클라우드 환경에서는 여러 VM의 I/O 요청이 뒤섞이는 **I/O Blender 효과**가 발생함. 이를 해결하기 위해 하이퍼바이저 레벨의 I/O 스케줄러(Deadline, CFQ 등)를 서비스 특성에 맞게 튜닝하고, 스토리지 QoS 기능을 통해 자원 경합을 제어해야 함.
