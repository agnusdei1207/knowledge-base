## Ⅰ. 개요
- **정의**: I/O 요청 큐를 재배열하여 디스크 헤드 이동 거리를 최소화하는 커널 스케줄링 기법임
- **배경/필요성**: 디스크 탐색 시간(Seek Time)이 I/O 지연의 주요 원인이므로 요청 순서 최적화가 필요함
- **비유**: 엘리베이터가 한 방향으로 이동하며 층별 승객을 태우는 것과 유사함 (SCAN)

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스케줄링 알고리즘별 특성 비교 | FCFS·SSTF·SCAN·C-SCAN 헤드 이동 패턴 | SSD 환경에서 탐색 시간 개념이 무의미해지는 점 구분 |

> 요약: 디스크 헤드 이동 최적화로 I/O 처리량을 향상시키는 기법임

## Ⅱ. 구성요소
```text
Application I/O Request
  |
  v
I/O Scheduler (Kernel)
  +-- Request Queue
  +-- Scheduling Algorithm (FCFS/SSTF/SCAN/C-SCAN)
  |
  v
Block Device Driver -> Disk Controller -> Disk
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Request Queue | 대기 중인 I/O 요청을 섹터 번호와 함께 보관하는 큐 | 엘리베이터 호출 목록 |
| Scheduling Algorithm | 큐 내 요청 처리 순서를 결정하는 정책 | 엘리베이터 운행 규칙 |
| Disk Controller | 스케줄러가 결정한 순서대로 헤드를 이동시키는 HW 제어기 | 엘리베이터 모터 |

> 요약: 요청 큐-스케줄링 알고리즘-디스크 컨트롤러 3단계로 구성됨

## Ⅲ. 절차
```text
I/O 요청 도착 -> 큐 삽입 -> 알고리즘 정렬 -> 헤드 이동·서비스
```
- 1단계: 애플리케이션 I/O 요청이 커널 I/O 스케줄러 큐에 도착함
- 2단계: 요청을 섹터 번호 기준으로 큐에 삽입하고 병합 가능 요청을 합침
- 3단계: 선택된 알고리즘(SCAN 등)에 따라 큐를 재정렬함
- 4단계: 정렬 순서대로 헤드를 이동시켜 데이터를 읽기/쓰기함

> 요약: 요청 병합·정렬 후 최적 순서로 디스크를 서비스함

## Ⅳ. 문제점
- FCFS 비효율: 요청 도착 순 처리로 헤드 이동 거리가 최악의 경우 전체 실린더를 왕복함
- SSTF 기아 현상: 헤드 근처 요청만 우선 처리되어 먼 트랙 요청이 무한 대기할 수 있음
- HDD 전제 한계: SSD는 탐색 시간이 없으므로 기존 스케줄링 알고리즘의 이점이 사라짐

> 요약: 헤드 이동 비효율·기아·매체 변화가 주요 문제임

## Ⅴ. 개선방안
1. 단기: SCAN/C-SCAN 채택으로 헤드 이동 거리를 균등화하여 FCFS 비효율 해소
2. 중기: Deadline·CFQ 스케줄러로 요청별 만료 시간을 설정하여 기아 현상 방지
3. 장기: SSD 환경에서 noop/mq-deadline 등 경량 스케줄러로 전환하여 불필요한 정렬 제거

> 요약: 알고리즘 고도화와 매체별 스케줄러 분리로 해결함

## Ⅵ. 전망
- 발전 방향: NVMe 멀티 큐 환경에서 BFQ·Kyber 등 I/O 우선순위 기반 스케줄러가 부상함
- 기술사적 판단: 저장 매체 혼용(HDD+SSD) 환경에서 계층별 스케줄링 정책 분리가 필요함
- 기술사 제언: 워크로드 프로파일링 후 매체·용도에 맞는 스케줄러를 선택 적용할 필요가 있음
