## 미리 알고가기

- 트랜잭션(Transaction): 데이터베이스의 상태를 변환시키는 하나의 논리적 작업 단위를 구성하는 연산들의 묶음임
- ACID: 트랜잭션이 안전하게 수행된다는 것을 보장하기 위해 데이터베이스가 지녀야 하는 4대 성질(원자성, 일관성, 고립성, 지속성)임
- MVCC(Multi-Version Concurrency Control): 동시성 제어 기법 중 하나로, 데이터에 접근할 때 여러 버전의 스냅샷을 활용하여 읽기와 쓰기 작업 간의 잠금 대기를 제거하는 방식임
- 회복(Recovery): 트랜잭션 실행 중 시스템 장애가 발생했을 때, 데이터베이스를 장애 이전의 일관된 상태로 복구하는 기술임
- 동시성 제어(Concurrency Control): 다수의 트랜잭션이 동시에 실행될 때 데이터베이스의 일관성을 해치지 않도록 트랜잭션 간의 간섭을 제어하는 기법임

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: 데이터 신뢰성의 기반 구조인 ACID 4대 성질과 이를 제어하는 로깅 및 동시성 제어 메커니즘을 규명하는 것을 최우선 축으로 설정함
- **절 구성 및 전개 흐름 이유**: 개요에서 완결성과 정합성을 정의하고, Ⅱ절에서 각 성질별 연관 특징을 상세 분석함. Ⅲ절에서 가용성을 지향하는 BASE 모델과 상호 보완 비교를 제시하고, Ⅳ절과 Ⅴ절을 각각 정적 구성요소와 트랜잭션 라이프사이클의 흐름도로 구분 설계하여 가시성을 확보함
- **전수 검수 완료 근거**: 제목, frontmatter, 본문, 비교표, Ⅴ절 절차 설명, 결론까지 총 5회 완독 및 전수 검수를 거쳐 어색한 중복 조사와 비문형 표현을 교정함

## Ⅰ. 개요

- **정의/개념**: ACID는 데이터베이스 트랜잭션의 올인원 반영($All-or-Nothing$), 제약조건 준수, 동시 연산 차단, 영구 저장을 규정하는 데이터 무결성 보장 원칙임
- **배경/필요성**: 다수의 클라이언트가 동시에 데이터에 접근하고 시스템 하드웨어 장애가 일어나는 환경에서도 데이터 파손을 막고 정상 상태로 복구하기 위해 트랜잭션 격리 및 로깅 제어 기준이 필요함

### 쉽게 이해하기 (학습용)
- 은행 송금 시 내 계좌에서 돈이 빠져나가는 일과 상대방 계좌에 돈이 입금되는 일이 도중에 멈춤 없이 통째로 한 번에 처리되거나 아예 취소되어 돈이 허공에 사라지지 않게 막는 규칙임

## Ⅱ. 특징

- **원자성($Atomicity$)**: 트랜잭션 내의 모든 연산이 데이터베이스에 모두 반영되거나, 아니면 전혀 반영되지 않아야($All-or-Nothing$) 함
- **일관성($Consistency$)**: 트랜잭션 수행 전과 후에 데이터베이스는 항상 정의된 도메인 제약과 비즈니스 규칙을 만족해야 함
- **고립성($Isolation$)**: 동시에 실행되는 여러 트랜잭션들이 서로 간섭하여 중간 연산 결과를 조회하거나 덮어쓰지 못하도록 차단함
- **지속성($Durability$)**: 성공적으로 완료($Commit$)된 트랜잭션의 결과는 시스템 장애가 발생하더라도 로그 복구를 통해 영구히 보존됨

### 쉽게 이해하기 (학습용)
- 금고에 물건을 넣을 때, 문을 완전히 닫고 잠그거나(원자성), 규격에 맞는 물건만 넣고(일관성), 다른 사람이 금고를 동시에 열지 못하게 하며(고립성), 화재가 나도 금고 내부 기록이 손상되지 않는(지속성) 형태임

## Ⅲ. 종류 및 비교

- 데이터의 엄격성을 추구하는 ACID와 대규모 분산 환경 가용성을 지향하는 BASE 모델을 비교함

| 판단 기준 | ACID 모델 | BASE 모델 |
|:---|:---|:---|
| **우선 가치** | 트랜잭션의 즉각적 데이터 정합성과 완전성을 보장함 | 시스템 가용성($Availability$)과 분산 확장성을 우선함 |
| **동작 방식** | 락($Lock$)과 트랜잭션 경계로 변경을 즉시 동기화함 | 비동기 복제와 사후 정합성 수렴($Eventual-Consistency$)을 사용함 |
| **일관성 보장** | 강한 일관성($Strong-Consistency$)을 상시 유지함 | 약한 일관성 하에 중간 불일치 상태가 일시적으로 존재함 |

### 쉽게 이해하기 (학습용)
- 돈 거래를 할 때 1원이라도 틀리면 즉시 거래를 멈추는 은행 회계 방식(ACID)과 SNS 좋아요 수가 각 사용자 기기마다 점차 다르게 보이다가 결국 일치하게 되는 방식(BASE)의 차이임

## Ⅳ. 구성요소 및 구조

- 트랜잭션 ACID를 데이터베이스 시스템 내부에서 구현하는 정적 구성임

```text
[트랜잭션 관리자 (Transaction Manager)]
         │
         ├─> [원자성 제어] ──(되돌리기 로그 / Undo Log)
         ├─> [일관성 규칙] ──(도메인 및 PK-FK 제약조건)
         ├─> [고립성 제어] ──(락 제어 및 MVCC 스냅샷)
         └─> [지속성 장치] ──(재실행 로그 / Redo Log)
```

| 설계 요소 | 설명 |
|:---|:---|
| **원자성 제어** | 트랜잭션 실패 시 데이터베이스를 이전 상태로 되돌리기 위해 변경 전 값을 $Undo$ 로그에 기록하고 롤백함 |
| **일관성 규칙** | 데이터베이스 스키마에 정의된 데이터 타입, 기본키, 외래키 등의 제약사항을 상시 유효성 검사함 |
| **고립성 제어** | 트랜잭션 격리 수준($Isolation-Level$)에 맞게 레코드 락($Lock$)을 걸거나 $MVCC$용 다중 버전 데이터를 제공함 |
| **지속성 장치** | 커밋된 변경 데이터를 디스크에 쓰기 전 $Redo$ 로그에 기록($Write-Ahead-Logging$)하고 체크포인트를 수행함 |

### 쉽게 이해하기 (학습용)
- 계약서 작성 시 잘못 쓰면 지울 지우개($Undo$)를 준비하고, 계약 규칙 서류(제약조건)를 두며, 계약 중 외부 개입을 막는 격리막(락)을 치고, 계약 도장을 찍은 뒤 장부 복사본($Redo$)을 백업 금고에 보관하는 구조임

## Ⅴ. 원리 및 절차 흐름도

- 트랜잭션이 시작되어 커밋되거나 비정상 장애 시 복구되는 동적 수명 주기임

```text
[작업 시작] ──> [검증 및 연산 수행] ──> [커밋 또는 롤백] ──> [로그 기반 복구]
```

1. **작업 시작**: 응용 프로그램이 트랜잭션 시작($Begin$)을 선언하고 필요한 세션 및 임시 메모리 버퍼 자원을 확보함
2. **검증 및 연산 수행**: $SQL$ 연산을 실행하면서 정의된 스키마 무결성 검증을 가동하고, 타 세션 접근 시 격리 수준 정책에 따라 대기함
3. **커밋 또는 롤백**: 모든 연산이 정상이면 완료($Commit$)하여 디스크에 로그를 기록하고, 실패 시 $Undo$ 데이터를 활용해 전체 취소($Rollback$)함
4. **로그 기반 복구**: 전원 공급 중단 등 시스템 장애 복구 시, $Redo$ 로그를 활용해 커밋 완료 데이터를 복원($Redo$)하여 최종 지속성을 충족함

### 쉽게 이해하기 (학습용)
- 장바구니 결제 버튼을 누르고(시작), 카드 한도와 보안 유효성을 검사받으며(검증), 이상 없을 시 승인 문자를 발송하고 에러 시 결제 취소를 진행하며(커밋/롤백), 통신 오류가 발생해도 카드사 내역서에 결제 결과가 남는(복구) 흐름임

## Ⅵ. 실무 사례

- **은행 계좌 이체 시스템**: 출금 계좌 잔액 감소와 입금 계좌 잔액 증가 연산을 하나의 트랜잭션으로 묶고 격리 수준을 $Serializable$ 또는 $Repeatable-Read$로 설정하여 잔액의 정밀 일관성을 제어함
- **데이터베이스 장애 복구**: 전원 오프 장애 발생 시 엔진이 재시작하면서 WAL($Write-Ahead-Log$) 프로토콜을 수행하여 커밋되었으나 디스크에 미반영된 데이터는 $Redo$하고, 커밋되지 않은 미완성 데이터는 $Undo$ 처리함

### 쉽게 이해하기 (학습용)
- 마트 포스기에서 결제 도중 정전이 발생했을 때, 포스기가 켜진 후 방금 결제 완료 도장이 찍힌 건은 영수증이 출력(Redo)되게 돕고 결제 승인 실패 건은 다시 처음부터 바코드를 찍게 초기화(Undo)하는 조치임

## Ⅶ. 결론

- 트랜잭션 ACID는 데이터의 모순을 예방하고 하드웨어 물리적 장애 환경에서도 비즈니스 연산 결과의 일관된 신뢰를 약속함
- 서비스 동시성이 극대화되는 실무 환경에서는 락 경합으로 인한 지연 속도 증가를 제어할 수 있도록 $MVCC$ 튜닝 및 상황에 맞는 완화된 격리 수준을 적용해야 함

### 쉽게 이해하기 (학습용)
- 고층 건물의 출입 게이트 보안을 강화하기 위해 모든 승객을 한 명씩 지문 검사(강한 격리)하면 대기 줄이 길어지므로, 구역별 안전 등급을 나누어 카드 키 태그(격리 수준 타협)로 원활한 흐름과 보안을 병행하는 전략과 같음
