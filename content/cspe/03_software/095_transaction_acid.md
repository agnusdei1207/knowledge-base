## 미리 알고가기

- 트랜잭션은 하나의 논리적 작업 단위를 이루는 연산 묶음임
- ACID는 원자성, 일관성, 고립성, 지속성을 뜻하는 데이터 신뢰성 기준임
- MVCC는 동시성 제어를 위해 여러 버전의 데이터를 활용하는 방식임

## Ⅰ. 개요

- **정의/개념**: 트랜잭션 ACID는 여러 데이터 연산을 하나의 논리적 작업 단위로 처리할 때 전부 반영되거나 전부 취소되고, 제약조건이 유지되며, 동시 실행 간 간섭이 통제되고, 커밋된 결과가 장애 후에도 보존되도록 하는 데이터 처리 신뢰성 원칙임.
- **배경/필요성**: 계좌 이체와 주문 결제처럼 중간 상태가 허용되지 않는 업무에서는 장애와 동시 요청이 있어도 데이터 정합성과 복구 가능성을 보장해야 함.

## Ⅱ. 특징

- 원자성으로 부분 완료 상태를 차단해 업무 실패 전파를 막음
- 일관성으로 제약조건과 업무 규칙이 깨지지 않게 유지함
- 고립성으로 동시 실행 간 읽기와 쓰기 간섭을 통제함
- 지속성으로 커밋 결과를 로그와 복구 절차로 보존함

## Ⅲ. 종류 및 비교

| 구분 | ACID | BASE |
|:---|:---|:---|
| 우선 가치 | 강한 정합성과 복구 가능성을 우선함 | 가용성과 확장성과 최종 일관성을 우선함 |
| 갱신 모델 | 즉시 일관성을 지향함 | 일시적 불일치를 허용하고 나중에 맞춤 |
| 얻는 장점 | 핵심 업무 처리 안정성이 높음 | 대규모 분산 처리와 확장에 유연함 |
| 주요 한계 | 분산 확장과 지연 비용이 커질 수 있음 | 중간 불일치를 견딜 업무 설계가 필요함 |

> 요약: ACID의 본질은 데이터베이스 기능 목록이 아니라 실패와 동시성이 있는 현실에서 핵심 업무 상태를 믿을 수 있게 유지하는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원자성 제어 | 되돌리기 로그와 롤백 절차로 부분 반영을 제거함 |
| 일관성 규칙 | 키와 제약조건과 업무 검증 규칙으로 올바른 데이터 상태를 유지함 |
| 고립성 제어 | 락과 MVCC와 격리 수준으로 동시성 간섭을 제어함 |
| 지속성 장치 | 재실행 로그와 체크포인트와 복구 절차로 커밋 결과를 보존함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 시작      | --> | 검증/연산 수행  | --> | 커밋 또는 롤백  | --> | 로그 기반 복구  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 시작**: 트랜잭션 경계를 설정하고 자원을 확보함
2. **검증과 연산 수행**: 제약조건과 동시성 제어 아래 연산을 수행함
3. **커밋 또는 롤백**: 성공 시 반영하고 실패 시 전부 취소함
4. **로그 기반 복구**: 장애 발생 시 커밋 상태를 복원함

## Ⅵ. 실무 적용 및 유의점

1. 계좌 이체와 결제 승인처럼 강한 정합성이 필요한 업무에서는 ACID가 필수지만 고립성 수준을 무조건 높이면 경합이 커지므로 작업 부하에 맞는 격리 수준을 고르고 잠금 대기 시간과 초당 트랜잭션 처리량으로 확인함
2. 대형 주문 처리 시스템에서는 트랜잭션 경계를 과도하게 넓게 잡으면 불필요한 락과 롤백 비용이 커지므로 업무 단위를 기준으로 경계를 재설계하고 평균 트랜잭션 범위와 롤백 비율로 확인함

## Ⅶ. 결론

ACID는 핵심 업무 데이터가 장애와 동시 요청 속에서도 믿을 수 있는 상태를 유지하게 만드는 처리 규율임.
