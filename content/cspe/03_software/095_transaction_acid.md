## 미리 알고가기

- 트랜잭션은 하나의 논리적 작업 단위를 이루는 연산 묶음임
- ACID는 원자성, 일관성, 고립성, 지속성을 뜻하는 데이터 신뢰성 기준임
- MVCC는 동시성 제어를 위해 여러 버전의 데이터를 활용하는 방식임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- ACID는 원자성·일관성·고립성·지속성과 로그·동시성 제어를 핵심 축으로 설명함
- 비교표는 ACID·BASE의 처리 단위·무결성·실패 처리·가용성을 대비함
- 계좌 이체와 주문 처리 DB는 잠금 대기·롤백 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: ACID는 트랜잭션의 전부 반영·취소, 제약 유지, 동시 실행 격리, 커밋 결과 보존을 규정하는 데이터 처리 원칙임
- **배경/필요성**: 장애와 동시 요청에서도 업무 상태와 커밋 결과를 복구하기 위해 트랜잭션의 실행·실패 처리 기준이 필요함

## Ⅱ. 특징

- 원자성으로 부분 반영을 롤백해 트랜잭션 이전 상태로 복원함
- 일관성으로 제약조건과 업무 규칙이 깨지지 않게 유지함
- 고립성으로 동시 실행 간 읽기와 쓰기 간섭을 통제함
- 지속성으로 커밋 결과를 로그와 복구 절차로 보존함

## Ⅲ. 종류 및 비교

| 판단 기준 | ACID | BASE |
|:---|:---|:---|
| 우선 가치 | 원자적 처리·무결성 제약·복구를 우선함 | 가용성·확장성·사후 수렴을 우선함 |
| 처리 단위 | 트랜잭션 경계 안의 변경을 전부 반영하거나 취소함 | 가용 노드에서 변경을 수락하고 복제본으로 전파함 |
| 실패 처리 | 롤백·복구 로그·격리로 트랜잭션 상태 보존 | 재시도·보상·병합으로 복제본 상태 수렴 |
| 주요 한계 | 분산 확장과 지연 비용이 커질 수 있음 | 중간 불일치를 견딜 업무 설계가 필요함 |

> 요약: ACID는 원자적 트랜잭션과 무결성 제약을, BASE는 가용성과 복제본의 사후 수렴을 우선함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 원자성 제어 | 되돌리기 로그와 롤백 절차로 부분 반영을 제거함 |
| 일관성 규칙 | 키와 제약조건과 업무 검증 규칙으로 올바른 데이터 상태를 유지함 |
| 고립성 제어 | 락과 MVCC와 격리 수준으로 동시성 간섭을 제어함 |
| 지속성 장치 | 재실행 로그와 체크포인트와 복구 절차로 커밋 결과를 보존함 |

> 요약: 롤백 로그가 원자성을, 제약조건이 일관성을, 락·MVCC가 고립성을, 재실행 로그가 지속성을 구현함.

## Ⅴ. 원리 및 절차 흐름도

1. **작업 시작**: 트랜잭션 경계를 설정하고 자원을 확보함
2. **검증과 연산 수행**: 제약조건과 동시성 제어 아래 연산을 수행함
3. **커밋 또는 롤백**: 성공 시 반영하고 실패 시 전부 취소함
4. **로그 기반 복구**: 장애 발생 시 커밋 상태를 복원함

> 요약: 제약조건과 동시성 제어 아래 트랜잭션을 실행하고 커밋·롤백 결과를 로그로 복구함.

## Ⅵ. 실무 사례

1. 계좌 이체 서비스는 업무 충돌에 맞는 격리 수준을 적용하고 잠금 대기 시간·초당 트랜잭션 수를 확인함
2. 주문 처리 DB는 트랜잭션 경계를 주문 상태 변경 단위로 제한하고 평균 잠금 시간·롤백 비율을 확인함

## Ⅶ. 결론

- ACID는 원자성·일관성·고립성·지속성으로 장애와 동시 요청의 데이터 상태를 통제함
