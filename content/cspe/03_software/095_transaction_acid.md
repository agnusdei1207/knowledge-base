## 미리 알고가기

- 트랜잭션은 하나의 논리적 작업 단위를 이루는 연산 묶음임
- ACID는 원자성 일관성 고립성 지속성을 뜻하는 데이터 신뢰성 기준임
- 장애 복구와 동시성 제어는 ACID를 실제로 구현하는 핵심 수단임

## Ⅰ. 개요

- **정의/개념**: 트랜잭션 ACID는 여러 데이터 연산을 하나의 논리적 작업 단위로 처리할 때 전부 반영되거나 전부 취소되고, 제약조건이 유지되며, 동시 실행 간 간섭이 통제되고, 커밋된 결과가 장애 후에도 보존되도록 하는 데이터 처리 신뢰성 원칙임
- **배경/필요성**: 계좌 이체와 주문 결제처럼 중간 상태가 허용되지 않는 업무에서는 장애와 동시 요청이 있어도 데이터 정합성과 복구 가능성을 보장해야 함

## Ⅱ. 특징

- 원자성으로 부분 완료 상태를 차단해 업무 실패 전파를 막음
- 일관성으로 제약조건과 업무 규칙이 깨지지 않게 유지함
- 고립성으로 동시 실행 간 읽기와 쓰기 간섭을 통제함
- 지속성으로 커밋 결과를 로그와 복구 절차로 보존함

## Ⅲ. 종류 및 비교

| 판단 기준 | ACID | BASE |
|:---|:---|:---|
| 우선 가치 | 강한 정합성과 복구 | 가용성과 확장성 |
| 갱신 모델 | 즉시 일관성 지향 | 최종 일관성 지향 |
| 강점 | 핵심 업무 처리 안정성 | 대규모 분산 처리 유연성 |
| 한계 | 분산 확장과 지연 비용 | 일시적 불일치 수용 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Atomicity Control | undo 로그와 rollback 절차로 부분 반영을 제거함 |
| Consistency Rule | 키와 제약조건과 업무 검증 규칙으로 데이터 상태를 올바르게 유지함 |
| Isolation Control | 락과 MVCC와 격리 수준으로 동시성 간섭을 제어함 |
| Durability Mechanism | redo 로그와 체크포인트와 복구 절차로 커밋 결과를 보존함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 시작      | --> | 검증/연산 수행  | --> | 커밋 또는 롤백  | --> | 로그 기반 복구  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 시작**: 트랜잭션 경계를 설정하고 자원을 확보함
2. **검증과 연산 수행**: 제약조건과 동시성 제어 아래 연산을 수행함
3. **커밋 또는 롤백**: 성공 시 반영하고 실패 시 전부 취소함
4. **로그 기반 복구**: 장애 발생 시 커밋 상태를 복원함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 고립성 수준을 무조건 높이면 경합이 증가해 처리량과 응답 시간이 크게 떨어질 수 있음
   - 해결방안: workload에 맞는 isolation level과 MVCC를 선택하고 lock wait time과 transaction throughput으로 검증함
2. 문제: 로그와 체크포인트 관리가 부실하면 커밋 이후 장애 복구 시간이 길어져 지속성 보장이 약해질 수 있음
   - 해결방안: log durability 정책과 recovery drill을 운영하고 recovery time objective와 redo loss rate로 검증함
3. 문제: 애플리케이션이 트랜잭션 경계를 과도하게 넓게 잡으면 불필요한 락과 롤백 비용이 커질 수 있음
   - 해결방안: business unit of work 기준으로 경계를 재설계하고 average transaction scope와 rollback rate로 검증함

## Ⅶ. 적용 사례

- 계좌 이체 시스템에서는 강한 정합성을 유지하고 확인 지표는 lock wait time과 transaction throughput임
- 전자결제 플랫폼에서는 복구 훈련을 수행하고 확인 지표는 recovery time objective와 redo loss rate임
- 주문 처리 서비스에서는 트랜잭션 범위를 최적화하고 확인 지표는 average transaction scope와 rollback rate임

## Ⅷ. 결론

ACID의 본질은 데이터베이스 기능 목록이 아니라 실패와 동시성이 존재하는 현실에서 핵심 업무 상태를 믿을 수 있게 유지하는 처리 규율임.
