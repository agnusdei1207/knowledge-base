## Ⅰ. 개요
- 정의: V-Model의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Reqs] ----------> [Acceptance]
   [Analysis] -----> [System]
    [Design] ----> [Integration]
     [Code] ---> [Unit]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 개발 단계 | 요구사항, 분석, 설계, 구현 단계 | 문제 출제 |
| 검증 단계 | 단위, 통합, 시스템, 인수 테스트 | 채점 및 검사 |
| 추적성 | 개발 산출물과 테스트 케이스 간 연결 | 정답 확인 |

> 요약: 개발과 테스트 단계를 대응시켜 품질을 보증하는 모델임.

## Ⅲ. 절차
- ASCII 흐름도
  Req -> Spec -> Design -> Code -> Unit -> Integ -> Sys -> Acc

1. 요구사항 정의: 사용자 요구 수집 및 인수 테스트 계획 수립함.
2. 시스템 설계: 아키텍처 정의 및 시스템 테스트 케이스 작성함.
3. 상세 설계: 모듈 설계 및 단위 테스트 케이스 작성함.
4. 테스트 수행: 코드 구현 후 작성된 TC 기반 역순 검증함.

> 요약: 상위 단계의 오류를 하위 검증 단계에서 체계적으로 포착함.

## Ⅳ. 문제점
- 각 단계가 순차적으로 진행되어 요구사항 변경 대응이 어려움.
- 개발 후반부에 테스트가 집중되어 결함 발견 지연 리스크 발생함.

## Ⅴ. 개선방안
- 테스트 설계 조기 수행 및 정적 분석 병행으로 결함 조기 발견함.
- 애자일 기법을 접목한 반복적 V-모델(Incremental V) 적용함.

## Ⅵ. 전망
- 고신뢰성 임베디드 및 자동차 SW 분야의 표준 모델로 지속 활용됨.
- CSF: 단계별 산출물의 무결성 확보와 엄격한 게이트 리뷰 운영임.
