## Ⅰ. 개요
- 정의: 동일 시스템 내 프로세스 통신을 위한 양방향 파일 기반 소켓과 부모-자식 간 흐름인 파이프
- 배경: 파일 디스크립터(FD) 추상화를 기반으로 한 스트림 형태의 통신 채널 구축 필요
- 출제 의도: 통신의 방향성(Uni/Bi-directional) 및 주소 지정 방식의 차이 이해

## Ⅱ. 구성요소
```
[ Pipe ] : P1 (Write) ===[ Buffer ]===> P2 (Read)
[ UDS  ] : P1 <===[ /tmp/sock ]===> P2 (Full-duplex)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 익명 파이프 | 부모-자식 간에만 사용 가능한 임시 채널 | 종이컵 전화기 |
| 이름 있는 파이프 | 파일 시스템에 경로가 존재하는 파이프 (FIFO) | 일방통행 터널 |
| UDS | 파일 경로를 주소로 사용하는 양방향 소켓 통신 | 사무실 내선 전화 |
> 요약: 파이프는 단순 단방향 흐름, UDS는 복잡한 양방향 통신에 적합함.

## Ⅲ. 절차
```
[Create Pipe] -> [fork()] -> [Close Unused FD] -> [Data Flow] (Pipe)
[Socket/Bind/Listen] -> [Connect] -> [Accept] -> [Read/Write] (UDS)
```
1. 파이프는 `pipe()` 호출 후 프로세스 복제를 통해 입출력 FD를 상속받아 사용
2. 파이프 데이터는 선입선출(FIFO) 원칙에 따라 커널 버퍼를 통해 전달
3. UDS는 서버가 소켓 파일을 생성(Bind)하고 클라이언트가 해당 경로로 연결 요청
4. 연결 성립 후 양방향 데이터 스트림 또는 데이터그램 방식으로 통신 수행
> 요약: 생성 방식(상속 vs 바인딩)에 따라 통신 상대방 범위가 결정됨.

## Ⅳ. 문제점
- 원인: 익명 파이프는 혈연 관계가 없는 프로세스 간에는 통신이 불가능함
- 원인: UDS는 네트워크 소켓과 유사한 오버헤드가 파이프보다 다소 높음

## Ⅴ. 개선방안
- (단기) 다수의 프로세스 연동 시 FIFO(Named Pipe)를 활용하여 경로 기반 통신 구현
- (중기) 성능이 중요한 대규모 요청 처리는 파이프 대신 UDS의 비차단(Non-blocking) 모드 활용
- (장기) 로컬/원격 통신 인터페이스를 소켓으로 단일화하여 아키텍처의 일관성 유지

## Ⅵ. 전망
- 도커 컨테이너와 호스트 간의 통신 수단으로 유닉스 도메인 소켓 활용도가 매우 높음
- 보안 정책(SELinux 등) 강화를 위해 소켓 파일에 대한 정교한 접근 제어 기술이 필수적으로 수반됨
