## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 목적 파일들을 하나로 결합하고 이를 메모리에 적재하여 실행 가능하게 함 |
| 필요성 | 분할 컴파일 지원, 라이브러리 공유 및 주소 할당/재배치 수행 |
| 출제 의도 | 정적/동적 연결 차이, 로더의 4대 기능(할당, 연결, 재배치, 적재) 이해 |

## Ⅱ. 구성요소
```text
[ Obj File A ] + [ Obj File B ] + [ Libs ]
       |               |            |
       +------( Linker )------------+
               |
        [ Executable File ]
               |
        ( Loader ) ----> [ Memory ]
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 링커 (Linker) | 여러 모듈 간의 외부 참조를 해결하여 연결함 | 조립 라인 |
| 로더 (Loader) | 프로그램을 실제 메모리 주소에 올리고 제어권 이양 | 숙소 안내원 |
| 심볼 테이블 | 변수나 함수의 이름과 주소 정보를 담은 자료구조 | 주소록 |
> 요약: 링커는 실행 파일을 만들고, 로더는 실행 중인 상태로 만듦.

## Ⅲ. 절차
```text
Allocation -> Linking -> Relocation -> Loading
    |           |            |           |
 (공간확보) (심볼연결) (주소보정) (메모리전송)
```
1. 할당(Allocation): OS로부터 프로그램을 실행할 메모리 공간을 확보함.
2. 연결(Linking): 각 목적 파일 간의 함수 호출 등 논리적 연결을 완성함.
3. 재배치(Relocation): 보조기억장치 기준 주소를 실제 할당된 물리 주소로 변경함.
4. 적재(Loading): 최종 주소 보정이 끝난 코드를 메모리 영역으로 전송함.
> 요약: 4단계 과정을 통해 정적인 파일이 동적인 프로세스로 전환됨.

## Ⅳ. 문제점
- 정적 링킹 시 동일한 라이브러리가 여러 실행 파일에 중복 포함되어 디스크 낭비.
- 로딩 시 주소 재배치 오버헤드로 인해 대규모 프로그램의 시작 속도 저하.

## Ⅴ. 개선방안
- 동적 링킹(DLL, Shared Lib) 기술을 사용하여 메모리 및 저장 공간 효율화.
- 지연 로딩(Lazy Loading)을 적용하여 필요한 시점에 모듈을 메모리에 적재.

## Ⅵ. 전망
- 컨테이너화: 링커/로더 수준의 의존성 문제를 이미지 단위로 캡슐화하여 배포 단순화.
- 보안 강화: ASLR(Address Space Layout Randomization)과 연동하여 로딩 시 주소 난수화.
