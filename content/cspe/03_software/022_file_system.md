## 미리 알고가기

- 파일 시스템은 저장장치 위에 파일과 디렉터리를 조직하는 운영체제 구조임
- 메타데이터는 파일 이름과 위치와 권한과 시간 정보를 의미함
- FAT와 NTFS와 ext4와 APFS는 대표적인 범용 파일 시스템 계열임

## Ⅰ. 개요

- **정의/개념**: 파일 시스템은 저장장치의 블록 공간을 파일과 디렉터리와 메타데이터 구조로 조직해 응용 프로그램이 데이터를 이름 기반으로 저장하고 조회하게 하는 운영체제 핵심 계층임
- **배경/필요성**: 단순 블록 장치는 사용자와 응용이 직접 다루기 어렵고 무결성과 권한과 복구 체계가 필요하므로, 저장 매체 특성에 맞는 파일 시스템 구조가 요구됨

## Ⅱ. 특징

- 데이터 블록과 메타데이터를 분리 관리해 이름 기반 접근을 제공함
- 디렉터리 구조와 권한 모델과 일관성 방식이 파일 시스템별 차이를 만듦
- SSD와 HDD와 모바일 저장장치처럼 매체 특성에 따라 최적 구조가 달라짐
- 성능뿐 아니라 복구성, 스냅샷, 암호화, 대용량 지원이 선택 기준이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | FAT | NTFS | ext4 | APFS |
|:---|:---|:---|:---|:---|
| 구조 특성 | 단순 테이블 기반 | 풍부한 메타데이터와 저널링 | 범용 리눅스 표준과 저널링 | copy-on-write와 스냅샷 중심 |
| 장점 | 호환성 높음 | 권한과 복구 기능 풍부 | 안정성과 성능 균형 | SSD 친화와 스냅샷 유리 |
| 한계 | 대용량과 보호 기능 약함 | 구조 복잡도 큼 | 고급 기능은 제한적 | 특정 플랫폼 중심 |
| 대표 환경 | 이동식 매체 | Windows 서버/클라이언트 | Linux 서버 | Apple 생태계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Superblock or Volume Header | 파일 시스템 전체 상태와 매개변수를 저장해 마운트와 복구의 출발점이 됨 |
| Directory Structure | 파일 이름과 메타데이터 위치를 연결해 계층적 탐색과 관리 편의를 제공함 |
| Allocation Metadata | FAT나 inode나 extent처럼 블록 배치를 기록해 성능과 공간 효율을 결정함 |
| Consistency Mechanism | journaling이나 copy-on-write 구조가 장애 후 복구 시간과 무결성을 좌우함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 파일 요청      | --> | 경로 해석      | --> | 블록 배치/조회 | --> | 메타데이터 갱신 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **파일 요청**: 응용 프로그램이 파일 생성이나 읽기나 쓰기를 요청함
2. **경로 해석**: 디렉터리 구조를 따라 대상 파일 위치를 찾음
3. **블록 배치 또는 조회**: 데이터 블록을 할당하거나 기존 위치를 참조함
4. **메타데이터 갱신**: 크기와 시간과 할당 정보를 기록함

## Ⅵ. 실무 적용 및 유의점

1. 리눅스 서버와 범용 저장장치에서는 매체 특성에 맞는 파일 시스템을 고르되 메타데이터 손상과 복구 시간이 운영성에 직접 영향을 주므로 journaling 여부와 할당 구조를 함께 보고 fs latency와 fsck recovery time으로 확인함
2. 이동식 매체나 플랫폼 고정 단말에서는 호환성 또는 스냅샷 같은 목적을 분명히 두되 작은 파일과 디렉터리 수가 많으면 메타데이터 탐색 비용이 커지므로 directory 구조와 allocation 튜닝을 적용하고 mount success rate와 directory lookup latency로 확인함

## Ⅶ. 결론

파일 시스템 선택은 저장장치 위에 파일을 놓는 문제가 아니라 매체 특성과 무결성과 복구 전략을 어떤 구조로 담을지 정하는 운영체제 설계 판단임.
