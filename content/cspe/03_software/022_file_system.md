# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 보조기억장치(Disk)에 데이터를 효율적으로 저장, 관리, 검색하기 위해 **OS가 제공하는 논리적인 자료구조와 체계**.
- **핵심 직관**: 거대한 서류 창고(디스크)를 관리하는 방식. 서류를 어떻게 분류할지, 어디에 있는지 목록(Index)을 어떻게 만들지, 남들이 못 보게 어떻게 잠글지(Permission)를 결정하는 시스템.
- **주요 파일 시스템**:
    - **FAT32**: 호환성 갑, 하지만 단일 파일 4GB 제한.
    - **NTFS**: 윈도우 표준. 보안, 대용량, 저널링(복구) 지원.
    - **ext4**: 리눅스 표준. 성능과 안정성의 균형.
    - **APFS**: 애플 최신. SSD 최적화, 스냅샷 강점.

## 깊이 이해
- **할당 방식 (Allocation)**:
    - **연속 할당**: 파일을 통째로 붙여서 저장. (빠르지만 단편화 심함)
    - **불연속 할당 (Linked)**: 조각조각 연결 리스트로 저장. (단편화 해결, 검색 느림)
    - **인덱스 할당 (Indexed)**: 인덱스 블록을 따로 둬서 위치를 한눈에 관리. (현대 표준 - **Inode** 방식)
- **Inode (Index Node)**: 유닉스/리눅스 파일 시스템의 심장. 파일의 이름만 빼고 모든 메타데이터(크기, 권한, 생성일, 데이터 블록 위치)를 담고 있는 구조체.
- **VFS (Virtual File System)**: 사용자가 어떤 파일 시스템(NTFS든 ext4든)을 쓰든 동일한 인터페이스(`open`, `read`, `write`)로 접근하게 해주는 추상화 계층.

## 연결 개념
- **File System Journaling (023)**: 갑자기 전원이 꺼져도 데이터가 안 깨지게 하는 기술.
- **Disk Scheduling (024)**: 디스크 헤드를 어떻게 움직여야 빨리 읽을지 결정.
- **VFS (025 연계)**: 다양한 파일 시스템을 하나로 묶는 마법.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 비휘발성 저장장치에 데이터를 영구 보존하기 위해 공간을 구획화하고, 파일의 **메타데이터와 실데이터**를 매핑하여 관리하는 운영체제의 핵심 서비스임.
> 2. **기술적 핵심**: 할당 방식(Inode, B-Tree), 단편화 관리, 성능 향상을 위한 **Page Cache**, 그리고 신뢰성을 위한 **Journaling** 기술이 집약되어 있음.
> 3. **가치**: 데이터의 무결성(Integrity) 보장과 대용량 데이터에 대한 신속한 접근 성능을 제공하여 응용 프로그램의 저장소 기반을 형성함.

## Ⅰ. 저장장치의 논리적 설계도, 파일 시스템의 개요
- **정의**: 저장매체에 파일을 기록, 저장, 관리하기 위한 OS의 논리적 구조와 규칙의 집합.
- **주요 기능**: 공간 관리(할당/회수), 파일 명명(Naming), 접근 제어(Security), 신뢰성 관리(Backup/Recovery).

## Ⅱ. 파일 할당 및 관리 방식 분석

### 1. 데이터 블록 할당 방식 비교
| 방식 | 원리 | 장점 | 단점 |
|:---:|:---|:---|:---|
| **연속 할당** | 연속된 물리 블록 점유 | I/O 성능 우수 | 외부 단편화 심각, 파일 확장 곤란 |
| **불연속 (Linked)** | 연결 리스트 형태 저장 | 단편화 없음 | 랜덤 액세스 불가능, 포인터 오버헤드 |
| **인덱스 (Indexed)** | Index 블록에 주소 저장 | **랜덤 액세스 우수**, 단편화 해결 | 인덱스 블록 자체의 공간 낭비 |

### 2. Inode 구조 (유닉스/리눅스 표준)
- **Metadata**: 파일 모드, 소유자, 크기, 시간 정보.
- **Block Pointers**:
    - **Direct Blocks**: 실제 데이터 주소 직접 지칭 (작은 파일용).
    - **Indirect Blocks**: 다른 인덱스 블록을 거쳐 참조 (대용량 파일용).

## Ⅲ. 주요 운영체제별 파일 시스템 비교

| 구분 | FAT32 | NTFS | ext4 | APFS |
|:---:|:---|:---|:---|:---|
| **제조사** | Microsoft | Microsoft | Open Source (Linux) | Apple |
| **특징** | 단순함, 높은 호환성 | **보안(ACL), 저널링** | **Extent 기반**, 대용량 지원 | **SSD 최적화**, 스냅샷 |
| **최대 파일** | 4GB | 16EB | 16TB | 8EB |
| **한계** | 대용량 지원 부족 | 호환성 제약 | 복구 복잡성 | 애플 전용 |

## Ⅳ. 파일 시스템의 성능 및 신뢰성 기술

1. **Page Cache**: 메모리의 일부를 파일 데이터 저장용으로 사용하여 디스크 I/O 횟수 감소.
2. **Journaling**: 메타데이터 변경 사항을 별도 영역(Journal)에 선기록하여 충돌 시 빠른 복구 보장.
3. **VFS (Virtual File System)**: 상위 계층에 통합된 API를 제공하여 다중 파일 시스템의 투명한 접근 지원.

## Ⅴ. 기술적 심화: Flash File System (F2FS)
- **개념**: SSD/SD카드 같은 낸드 플래시 메모리의 특성(쓰기 전 삭제 필요)을 고려하여 설계된 삼성전자의 파일 시스템.
- **특징**: **Copy-on-Write** 기반의 로그 구조 파일 시스템을 채택하여 쓰기 성능 향상 및 수명 연장.

## Ⅵ. 기술사 관점의 결론 및 제언
- 파일 시스템은 **'속도(Performance)'와 '안전(Safety)'** 사이의 지속적인 균형 감각이 필요함.
- **실무 제언**: 고성능 DB 운영 시 파일 시스템의 **저널링 모드(Writeback vs Ordered)** 설정을 통해 성능과 데이터 안전성 중 우선순위를 조정하거나, SSD 환경에서는 **TRIM** 명령 최적화를 통해 장기적인 쓰기 성능 저하를 방지해야 함.
