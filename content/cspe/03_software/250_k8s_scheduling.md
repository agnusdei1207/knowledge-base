## Ⅰ. 개요
- 정의: 워크로드(Pod)를 최적의 노드에 배치하고 시스템 자원을 효율적으로 배분하는 기술임
- 배경: 수천 개의 노드로 구성된 대규모 클러스터의 자원 효율 극대화 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 스케줄링 | Filtering, Scoring | 매우높음 |
| 리소스 제어 | Requests/Limits, QoS | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ Pod 생성요청 ] -> [ API Server ] -> [ Scheduler ]
                                            |
  [ Worker Node 1 ] <--- (선택) --- [ Filtering / Scoring ]
  [ Worker Node 2 ]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 노드 필터링 | 자원 부족 등 조건 미달 노드를 후보에서 제외 | 입사 지원 자격 검토 |
| 노드 스코어링 | 가중치를 계산하여 가장 적합한 노드에 점수 부여 | 면접 점수 합산 |
| Requests/Limits | 컨테이너가 사용할 자원의 최소 보장량과 최대 제한량 | 기본급과 인센티브 상한 |

> 요약: 규칙 기반의 필터링과 점수 계산을 통해 Pod의 거처를 결정함

## Ⅲ. 절차
- ASCII 흐름도
  [Pod 감시] -> [노드 필터링] -> [노드 우선순위] -> [바인딩 실행]
  (Watch Event)   (Predicate)     (Priority)       (Node Assign)

- 4단계 설명
1. 대기: 스케줄러가 노드가 지정되지 않은 신규 Pod 생성을 감지함
2. 필터링: CPU/메모리 여유, 포트 중복, 노드 셀렉터 등을 체크하여 노드 선별함
3. 우선순위: 자원 분포, 이미지 보유 여부 등을 고려하여 최적 노드를 선정함
4. 바인딩: 선정된 노드 정보를 API 서버에 기록하고 해당 노드의 Kubelet에 전달함

> 요약: 정해진 알고리즘에 따라 클러스터 전체의 균형을 맞추며 Pod을 배치함

## Ⅳ. 문제점
- 특정 노드에 자원이 편중되거나 파편화되어 전체 활용률이 떨어지는 현상 발생함
- 리소스 제한(Limits)이 너무 엄격할 경우 일시적 부하에도 Pod이 강제 종료됨

## Ⅴ. 개선방안
- (단기) 오토스케일링(HPA/VPA/CA)을 연동하여 부하에 따라 자원을 유연하게 확장함
- (중기) 선점(Preemption) 및 축출(Eviction) 정책을 세분화하여 우선순위 관리함
- (장기) AI 기반 예측 스케줄링을 도입하여 트래픽 폭증 전 선제적으로 자원 배치함

## Ⅵ. 전망
- GPU 등 특수 하드웨어 자원을 고려한 'Hardware-aware Scheduling' 중요해짐
- 탄소 효율을 고려하여 전력 소모가 적은 노드에 우선 배치하는 정책이 부상함
