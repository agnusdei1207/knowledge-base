## Ⅰ. 개요
- 정의: 장애 발생 시에도 서비스를 지속하고 신속하게 정상 상태로 복구하는 능력임
- 배경: 서비스 중단 시 발생하는 경제적 손실 방지 및 비즈니스 연속성(BCP) 확보 필요
- 출제 의도: 결함 내성(Fault Tolerance) 설계 및 복구 전략(MTTR 단축) 수립 역량 평가

## Ⅱ. 구성요소
- ASCII 구조+------+
  | Node1 |----[Heartbeat]----| Node2 |
  | (Act) |                   | (Stb) |
  +-------+                   +-------+
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 가동률(MTBF) | 전체 운영 시간 대비 정상 가동 시간의 비율 | 무고장 주행 거리 |
| 이중화(Redundancy)| 장애 대비 예비 자원을 구성하는 방식 | 스페어 타이어 |
| 장애 조치(Failover)| 장애 감지 시 대기 자원으로 자동 전환 | 비상 발전기 가동 |
> 요약: 하트비트 등을 통한 장애 감지와 이중화 구조를 통한 무중단 서비스를 지향함

## Ⅲ. 절차
- ASCII 흐름도
  Fault Detect -> Isolation -> Failover -> Repair/Reintegrate
- 4단계 설명
1. Fault Detect: 헬스 체크, 워치독 등을 통해 장애 발생 여부 실시간 감시함
2. Isolation: 장애 전파 방지를 위해 서킷 브레이커(Circuit Breaker) 등으로 격리함
3. Failover: 서비스 중단 없이 예비 노드로 부하를 즉시 전환함
4. Repair/Reintegrate: 장애 원인 제거 후 원래 노드를 클러스터에 재편입함
> 요약: 장애를 감지-격리-전환하고 사후 복구 과정을 통해 가용성을 유지함

## Ⅳ. 문제점
- 원인이 명시된 문제/한계: 데이터 불일치(Split Brain) 현상 발생 시 시스템 무결성 훼손됨

## Ⅴ. 개선방안
- Ⅳ의 문제에 대응하는 방안: 쿼럼(Quorum) 기반 의사결정 및 정족수 메커니즘 적용함

## Ⅵ. 전망
- 발전 방향: 카오스 엔지니어링(Chaos Engineering)을 통한 능동적 장애 내성 검증 확산
- CSF: 단일 장애 지점(SPOF)의 완전 제거와 정기적인 재해 복구(DR) 훈련이 필수임
