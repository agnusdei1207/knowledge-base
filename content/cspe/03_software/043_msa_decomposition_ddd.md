## 핵심 인사이트 (3줄 요약)
- 거대한 시스템을 마이크로서비스로 쪼갤 때, 기술(프론트/백)이 아닌 비즈니스 도메인(결제, 배송) 기준으로 경계를 나누는 전략.
- 이 경계를 찾기 위한 가장 강력한 도구가 도메인 주도 설계(DDD)의 '바운디드 컨텍스트(Bounded Context)' 개념임.
- 무작정 작게 쪼개면 네트워크 통신 지옥(Distributed Monolith)이 되므로, 응집도(Cohesion)가 높은 기능들을 한 덩어리로 묶어 트랜잭션을 보호하는 것이 핵심.

## Ⅰ. 개요 및 필요성
- **개요**: 모놀리식 애플리케이션을 여러 개의 독립적인 마이크로서비스로 분할(Decomposition)하는 아키텍처 설계 기법.
- **필요성**: MSA 도입 시 가장 큰 난관은 "어떻게, 얼마나 작게 쪼갤 것인가?"임. 잘못 쪼개면 서비스 간 잦은 API 통신으로 성능이 저하되고, DB 트랜잭션 관리가 불가능해져 오히려 모놀리스보다 못한 시스템이 됨.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **주요 분해 전략 (Decomposition Patterns)**:
  1. **비즈니스 역량(Business Capability) 기반 분해**: 조직의 비즈니스 부서(예: 마케팅, 회계, 배송) 기준으로 분할.
  2. **하위 도메인(Sub-domain) 기반 분해 (DDD)**: 시스템을 도메인 모델로 분석하고, 명확한 책임 경계(Bounded Context)를 기준으로 분할.
- **DDD 기반 분해 핵심 절차**:
  1. **이벤트 스토밍(Event Storming)**: 도메인 전문가와 개발자가 모여 비즈니스 이벤트 발생 순서를 포스트잇으로 시각화.
  2. **애그리거트(Aggregate) 도출**: 강한 트랜잭션 일관성이 필요한 객체들의 묶음(예: 주문+주문상세)을 정의.
  3. **바운디드 컨텍스트 정의**: 애그리거트들을 묶어 독립적인 생명주기를 갖는 마이크로서비스 후보로 식별.

```text
[ 도메인 주도 설계(DDD) 기반 MSA 분해 ]

 (거대 시스템)        ➡️    (Bounded Context 1)     +    (Bounded Context 2)
 E-Commerce 도메인           [ 주문 (Order) MSA ]           [ 배송 (Delivery) MSA ]
                                 - Order Entity                  - Delivery Entity
                                 - OrderLine Entity              - Address Value Object
                             (주문 트랜잭션 완결성 보장)        (배송 트랜잭션 완결성 보장)
```
---
## Ⅲ. 비교 및 연결
| 분해 전략 | 특징 및 장단점 | 적용 시점 |
|---|---|---|
| **비즈니스 역량 기반** | 조직 구조와 일치하여 거버넌스가 직관적 / 도메인이 복잡해지면 한계 | 비즈니스 구조가 명확하고 정적인 경우 |
| **하위 도메인 (DDD)** | 데이터와 로직의 응집도가 극대화됨 / 학습 곡선이 매우 높음 | 도메인 로직이 고도로 복잡한 엔터프라이즈 |
| **트랜잭션 기반** | 2PC를 피하기 위해 분산 트랜잭션을 묶어버림 / 서비스가 비대해질 수 있음 | 성능과 데이터 정합성이 최우선인 금융권 |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **단어의 문맥 파악 (Ubiquitous Language)**: 똑같은 "상품(Product)"이라는 단어도 카탈로그 서비스에서는 '이미지와 설명'이고, 재고 서비스에서는 '잔여 수량'임. 이를 하나의 DB 테이블로 묶지 않고 서비스별로 찢어내는(분할) 것이 DDD의 핵심 철학임.
- **스트랭글러 피그 패턴 (Strangler Fig Pattern)**: 실무에서 모놀리스를 한 번에 MSA로 빅뱅(Big-Bang) 전환하는 것은 자살 행위임. 외곽의 덜 중요한 도메인부터 하나씩 DDD로 떼어내어 점진적으로 전환하는 리팩토링 전략을 구사해야 함.
---
## Ⅴ. 기대효과 및 결론
- 도메인 중심의 분해는 각 서비스가 높은 응집도와 낮은 결합도를 유지하게 하여, 타 서비스의 영향 없이 자유롭게 코드를 수정하고 배포할 수 있는 진정한 MSA의 이점을 제공함.
- 완벽한 서비스 분해는 한 번에 이루어지지 않으며, 비즈니스의 성장에 따라 바운디드 컨텍스트를 병합(Merge)하거나 재분할(Split)하는 진화적 아키텍처 관점을 견지해야 함.

### 👶 어린이를 위한 3줄 비유 설명
1. 커다란 피자 한 판(모놀리스)을 친구들과 나눠 먹으려면 예쁘게 조각을 내야 해요(서비스 분해).
2. 페퍼로니는 페퍼로니끼리, 불고기는 불고기끼리 맛이 안 섞이게 자르는 선을 '바운디드 컨텍스트'라고 불러요.
3. 이렇게 잘 쪼개 놓으면, 페퍼로니 피자만 더 구워서(확장) 먹고 싶을 때 다른 피자는 건드리지 않아도 된답니다!
