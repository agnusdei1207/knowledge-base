## 미리 알고가기

- WASM 코어는 계산·메모리 명령을 정의하지만 파일·네트워크 같은 시스템 인터페이스는 정의하지 않음
- WASI는 WASM 프로그램이 시스템 기능을 이식 가능한 인터페이스로 사용하도록 정한 표준군임
- 권한 기반 보안은 프로그램이 호스트에서 명시적으로 받은 자원만 사용하게 함
- WIT는 컴포넌트의 함수·타입·자원 인터페이스를 기술하는 언어임
- 리소스 핸들은 파일·소켓 같은 호스트 자원을 컴포넌트에 직접 노출하지 않고 참조하게 함
- WASI 구현 범위와 인터페이스 버전은 런타임별로 확인해야 함

## 작성 근거(검토용)

- WASI는 권한 기반 자원 접근, WIT 인터페이스, 런타임 구현, 버전 호환성을 핵심 축으로 설명함
- 비교표는 WASI 0.1·0.2·0.3의 API 모델·조합·비동기 처리·적합 조건을 같은 수준에서 대비함
- 절차는 호스트가 권한을 부여하고 컴포넌트 호출을 런타임이 중개하는 실제 순서를 따름

## Ⅰ. 개요

- **정의/개념**: WASI는 WASM 모듈·컴포넌트가 파일·네트워크·시계·난수 같은 시스템 기능을 권한 기반 표준 인터페이스로 호출하게 하는 규격군임
- **배경/필요성**: WASM 코드를 여러 런타임에서 실행하며 OS별 시스템 호출 의존성과 호스트 권한을 줄이기 위해 공통 인터페이스가 필요함

## Ⅱ. 특징

- 컴포넌트는 기본 호스트 권한 없이 시작하고 런타임이 부여한 자원만 사용함
- 시스템 기능을 WIT 인터페이스로 정의해 언어·OS별 구현과 응용 코드를 분리함
- 파일·소켓 같은 자원은 리소스 핸들로 전달해 접근 범위와 수명을 통제함
- 인터페이스 버전과 런타임 구현 상태가 다를 수 있어 배포 전 호환성 검증이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | WASI 0.1 | WASI 0.2 | WASI 0.3 |
|:---|:---|:---|:---|
| API 모델 | POSIX를 참고한 코어 모듈 함수 | WIT 기반 컴포넌트 인터페이스 | WIT 기반 컴포넌트 인터페이스 |
| 조합 단위 | 모듈 import·export | 타입이 지정된 컴포넌트 | 타입이 지정된 비동기 컴포넌트 |
| 비동기 처리 | 런타임별 방식 사용 | 동기 인터페이스 중심 | `future`·`stream` 기반 비동기 지원 |
| 언어 연동 | 메모리·정수형 ABI 변환 필요 | Canonical ABI로 고수준 타입 변환 | Canonical ABI와 비동기 호출 규약 사용 |
| 적합 조건 | 기존 런타임 호환이 필요 | 동기 컴포넌트 조합이 필요 | 비동기 서버·스트림 컴포넌트가 필요 |

> 요약: WASI는 코어 모듈 중심 0.1에서 WIT 컴포넌트와 비동기 인터페이스를 지원하는 방향으로 확장됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| WIT 인터페이스·월드 | 컴포넌트가 가져오고 내보낼 함수·타입·자원을 정의함 |
| WASM 컴포넌트 | 업무 코드와 필요한 WASI import를 패키징함 |
| WASI 런타임 | 인터페이스 호출을 검증하고 호스트 구현에 연결함 |
| 권한·리소스 핸들 | 파일·소켓·시계 같은 자원의 접근 범위와 수명을 제한함 |
| 호스트 구현 | OS 기능을 WASI 인터페이스에 맞춰 수행하고 결과를 반환함 |

```text
WASM 컴포넌트 -> WIT·WASI import -> 런타임 -> 권한·리소스 핸들 -> 호스트 기능
```

> 요약: WIT 계약에 따라 런타임이 컴포넌트 호출을 허용된 호스트 자원에만 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
권한 구성 -> 컴포넌트 인스턴스화 -> WASI 호출 -> 리소스 검증 -> 호스트 실행 -> 결과 반환
```

1. **권한 구성**: 호스트가 사용할 디렉터리·소켓·환경 정보의 범위를 정함
2. **인스턴스화**: 런타임이 WIT import와 호스트 구현을 연결함
3. **WASI 호출**: 컴포넌트가 인터페이스 함수에 필요한 인수와 리소스 핸들을 전달함
4. **리소스 검증**: 런타임이 요청 자원이 부여된 권한 범위인지 확인함
5. **호스트 실행**: 호스트가 시스템 기능을 수행하고 표준 타입으로 결과를 반환함

> 요약: 런타임은 컴포넌트의 WASI 호출을 권한·리소스 범위와 대조한 뒤 호스트 기능에 연결함.

## Ⅵ. 실무 사례

1. 문서 변환 플러그인은 읽기 전용 디렉터리만 부여하고 권한 거부·처리 지연을 확인함
2. 서버 함수는 WASI 네트워크 대상을 제한하고 연결 거부·인터페이스 호환 실패를 확인함

## Ⅶ. 결론

- WASI는 WASM의 시스템 기능을 이식하려는 경우 인터페이스 버전·런타임 지원·부여 권한을 함께 확인함
