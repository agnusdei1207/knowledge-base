## Ⅰ. 개요
- 정의: 원본 코드에 인위적으로 오류(돌연변이)를 주입하여 테스트 데이터의 결함 발견 능력을 측정하는 기법
- 배경: 높은 코드 커버리지가 반드시 테스트 케이스의 유효성을 보장하지 않음을 보완
- 출제 의도: 돌연변이 생성 원리, '살아남은 돌연변이(Live Mutant)' 및 '살해(Killed)' 개념 이해

## Ⅱ. 구성요소
- 구조도
  [Original Code] -> [Mutation Operators] -> [Mutant Code #1, #2, ...]
                                                  |
  [Test Suite] -----------------------------------+

- 구성요소 표
| 용어 | 설명 | 비유 |
| :--- | :--- | :--- |
| 돌연변이(Mutant) | 소스 코드를 미세하게 수정한 버전 | 가짜 범인 |
| 살해(Killed) | 테스트 케이스가 오류를 찾아낸 상태 | 범인 검거 |
| 생존(Live) | 오류를 주입했음에도 테스트를 통과한 상태 | 범인 도주 |
> 요약: 테스트 케이스 자체가 얼마나 예리한지(품질)를 평가하는 테스팅

## Ⅲ. 절차
- 흐름도
  돌연변이 생성 -> 테스트 수행 -> 결과 분석 -> 테스트 케이스 강화
- 4단계 설명
1. 돌연변이 생성: 산술 연산자 교체( + -> - ) 등 다양한 연산자를 적용한 코드 생성
2. 테스트 수행: 생성된 수많은 돌연변이 코드들에 대해 기존 테스트 스위트 실행
3. 결과 분석: 테스트를 통과한(생존한) 돌연변이 식별 및 원인 파악
4. 케이스 강화: 생존한 돌연변이를 잡을 수 있도록 새로운 테스트 케이스를 추가/수정
> 요약: 돌연변이 점수(Mutation Score)를 높여 테스트의 신뢰성 극대화

## Ⅳ. 문제점
- 대규모 프로젝트에서 생성되는 돌연변이 수가 너무 많아 테스트 수행 비용/시간 과다
- 논리적으로 원본과 동일한 기능을 수행하는 등가 돌연변이(Equivalent Mutant) 판별 난해

## Ⅴ. 개선방안
- 주요 로직에 한정하여 돌연변이를 생성하는 샘플링 기법 및 증분 테스트 도입
- 자동화된 도구(Pitest 등) 활용 및 병렬 처리를 통한 수행 속도 최적화

## Ⅵ. 전망
- AI가 코드의 맥락을 분석하여 의미 있는 돌연변이만을 선별 생성하는 기술 발전
- CSF: 단순히 커버리지를 높이는 것을 넘어, 테스트 데이터의 변별력 확보 주력
