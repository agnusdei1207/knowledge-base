## Ⅰ. 개요
- 정의: 동적으로 할당된 메모리 중 더 이상 사용되지 않는 영역을 자동으로 회수하는 기법
- 배경: 개발자의 수동 메모리 해제 부담 경감 및 메모리 릭(Leak) 방지를 통한 안정성 확보
- 출제 의도: 참조 카운팅, 마킹, 세대별 관리 등 다양한 GC 전략의 트레이드오프 이해

## Ⅱ. 구성요소
```
[ Mark-and-Sweep ]     [ Copying GC ]        [ Generational ]
1. Mark (Reachable)    +------+------+       +-----+-----+-----+
2. Sweep (Unmarked)    | From | To   |       | Eden| S0/1| Old |
                       +------+------+       +-----+-----+-----+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Root Set | GC 탐색의 시작점이 되는 참조 (Stack, Static 변수 등) | 가계부 뿌리 |
| Reachability | 루트로부터 도달 가능한지 여부에 따른 사용 판별 | 연락 닿는 지인 |
| STW (Stop-The-World) | GC 수행을 위해 애플리케이션 실행을 일시 중단 | 청소 중 영업 중단 |
> 요약: 도달 가능성(Reachability)을 기준으로 유효 자원을 선별하고 나머지를 회수함.

## Ⅲ. 절차
```
[Trigger] -> [Marking] -> [Sweeping/Compacting] -> [Resume]
```
1. 메모리 임계치 도달 또는 시스템 여유 시 GC 스레드가 가동됨
2. Root Set부터 시작하여 참조를 추적해 사용 중인 객체에 마크(Mark) 표시
3. 마크되지 않은 객체들을 메모리에서 해제(Sweep)하여 빈 공간 확보
4. 파편화 방지를 위해 살아남은 객체들을 한곳으로 모으는 압축(Compaction) 병행
> 요약: 중단 - 식별 - 회수 - 정리의 단계를 거쳐 메모리를 재정비함.

## Ⅳ. 문제점
- 원인: GC 수행 중 발생하는 STW 지연 시간으로 인해 실시간성이나 응답성이 저하됨
- 원인: 참조 카운팅 방식의 경우 순환 참조(Circular Reference) 발생 시 메모리 회수 불가

## Ⅴ. 개선방안
- (단기) 세대별 가비지 컬렉션(Generational GC) 기법으로 탐색 범위 최소화 및 효율 증대
- (중기) 애플리케이션 실행과 병행하여 GC를 수행하는 동시성(Concurrent) GC 도입
- (장기) ZGC, Shenandoah와 같이 테라바이트 급 메모리에서도 밀리초 단위 지연을 보장하는 기술 적용

## Ⅵ. 전망
- 대용량 데이터 처리 수요에 따라 힙 크기에 상관없이 일정한 지연 시간을 보장하는 기술이 핵심 경쟁력임
- 하드웨어 보조 GC 가속기 등 소프트웨어 한계를 하드웨어와 협력하여 극복하려는 시도 지속
