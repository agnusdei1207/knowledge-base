# 📖 【암기용】 개념 완전 이해

> 목적: 초개인화 서비스를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 초개인화 서비스는 **개인별 행동 로그**와 **실시간 컨텍스트**(위치·시간·재고·날씨 등)를 결합해 추천·가격·메시지·UI를 사용자 단위로 동적 조정하는 서비스 모델이다.
- **왜 필요한가**: 세그먼트(20대 여성, VIP 등) 단위 마케팅은 같은 그룹 안에서도 개인차가 크다. 초개인화는 그룹이 아니라 "이 사람이 지금 이 순간 무엇을 원하는가"를 예측해 전환율과 체류 시간을 끌어올린다.
- **핵심 직관**: 같은 메뉴판을 모두에게 주는 대신, 알레르기·예산·날씨·이전 주문 이력을 보고 그 사람만을 위한 추천 메뉴를 즉석에서 짜주는 단골 가게 방식이다.

## 핵심 용어 정리 표 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 초개인화 서비스 | 개인 행동+실시간 맥락 기반 동적 경험 제공 (상위 개념) | 단골에게 맞춤 추천하는 가게 |
| CDP (Customer Data Platform) | 여러 채널의 고객 데이터를 하나의 프로필로 통합·관리 | 흩어진 고객 파일을 한 폴더로 합치기 |
| Feature Store | 모델이 즉시 쓸 수 있게 가공된 특징(feature) 값을 저장·서빙하는 저장소 | 조리된 재료를 미리 꺼내두는 준비대 |
| 추천·랭킹 모델 | 후보를 만들고 점수를 매겨 순서를 정하는 2단 모델 구조 | 예선(후보 추리기) + 본선(순위 매기기) |
| Next Best Action | 지금 이 사용자에게 가장 유효할 다음 행동(추천·메시지)을 선택 | 그 순간 가장 어울리는 제안 고르기 |
| 실험 플랫폼 (A/B Test) | 일부 사용자에게만 새 로직을 노출해 효과를 측정 | 신메뉴를 일부 손님에게만 먼저 내보는 시식회 |
| Consent (동의) | 개인 데이터 수집·활용에 대한 사용자 승낙 상태 | 사진 촬영 전에 받는 허락 |
| Filter Bubble | 비슷한 추천만 반복되어 사용자가 다른 선택지를 못 보는 현상 | 매번 같은 메뉴만 추천받아 새 메뉴를 모르게 됨 |
| Decision API | 실시간으로 다음 행동을 계산해 반환하는 서비스 인터페이스 | 즉석에서 답을 내주는 안내 창구 |

## 깊이 이해

### 세그먼트 마케팅과 무엇이 다른가
- 세그먼트 마케팅은 "20대 여성"이라는 그룹 전체에 같은 배너를 뿌린다. 그룹 안에는 운동을 좋아하는 사람도, 독서를 좋아하는 사람도 섞여 있어 적중률이 낮다.
- 초개인화는 개인 단위 행동 로그(최근 검색 3건, 장바구니 상품, 방문 시간대)와 그 순간의 맥락(현재 위치, 재고, 남은 할인 시간)을 함께 넣어 "이 사람에게 지금" 맞는 항목을 고른다. 같은 사람이라도 아침에 보는 추천과 저녁에 보는 추천이 달라질 수 있다는 게 세그먼트 방식과의 근본 차이다.

### 데이터가 추천으로 이어지는 경로
- 사용자가 앱에서 클릭·검색·구매 이벤트를 발생시키면 이벤트는 CDP로 모여 하나의 고객 ID로 통합된다 — 같은 사람이 앱·웹·매장에서 남긴 흔적을 합치는 ID 매칭 과정이다.
- 이 통합 프로필에서 Feature Store가 "최근 7일 조회 카테고리", "평균 구매 단가" 같은 특징 값을 미리 계산해둔다. 추천 요청이 오면 랭킹 모델이 이 특징들과 실시간 이벤트(방금 본 상품)를 입력받아 후보를 점수화하고, Decision API가 상위 항목을 반환한다.

### 실시간성을 수치로 이해하기 (feature freshness)
- 사용자가 방금 검색한 상품이 5분 뒤에도 추천에 반영되지 않으면, 그 사이 사용자는 이미 관심을 잃었을 수 있다. 그래서 feature freshness(특징 값이 실제 이벤트를 반영하기까지 걸리는 시간)를 5분 이하로 관리하는 것이 일반적 기준이다.
- Decision API의 응답 지연이 p95 100ms를 넘으면 화면 로딩이 늦어져 이탈로 이어지므로 지연도 함께 관리한다.

### A/B 테스트로 uplift를 계산하는 법
- 초개인화 효과는 "안 했으면 어땠을까"를 직접 알 수 없으므로 대조군과 비교한다. 예를 들어 대조군(기존 추천) 10,000명 중 300명이 구매하면 전환율(CVR) 3.0%, 실험군(초개인화 추천) 10,000명 중 330명이 구매하면 CVR 3.3%다.
- uplift는 (3.3-3.0)/3.0 = 10%로 계산한다. 이 수치가 목표 기준(예: 5% 이상)을 넘어야 전사 적용을 결정한다.

### Filter Bubble을 막는 원리
- 랭킹 모델이 과거 클릭 패턴만 강화 학습하면, 이미 좋아한 카테고리만 계속 추천해 다른 상품을 볼 기회가 사라진다. 이를 막기 위해 추천 결과 중 일정 비율(예: 20%)을 exploration(탐색) 슬롯으로 배정해 새로운 카테고리를 섞고, 이 비율을 diversity 지표로 관측한다.

### 흔한 오해
- 초개인화는 "개인정보를 최대한 많이 모으는 것"이 아니다. 동의 없는 데이터, 목적 외 사용은 규제 위반과 신뢰 붕괴로 이어진다. 필요한 최소 데이터만 동의 범위 안에서 쓰고, 삭제 요청이 오면 프로필과 파생 특징까지 함께 삭제하는 구조(데이터 최소화·목적 제한)가 초개인화 설계의 전제 조건이다.

## 연결 개념
- CDP — 여러 채널 데이터를 하나의 고객 프로필로 통합하는 기반 시스템
- 추천 시스템 (Recommendation System) — 후보 생성과 랭킹을 수행하는 핵심 모델 계층
- Privacy by Design — 동의·최소 수집·목적 제한을 설계 단계에 내장하는 원칙

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 초개인화는 추천 모델 설명이 아니라 데이터 동의, 실시간 특징, 실험, 개인정보 통제를 포함한 서비스 설계로 답해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 초개인화 서비스는 개인별 행동·맥락·선호 데이터를 기반으로 콘텐츠, 추천, 메시지, UI를 동적으로 제공하는 서비스 모델이다.
> 2. **가치**: 전환율 uplift, 클릭률, 체류 시간, 이탈률 같은 비즈니스 지표와 동의율, 삭제 요청 처리 같은 개인정보 지표를 함께 관리한다.
> 3. **판단 포인트**: 실시간성, 데이터 품질, 모델 편향, 개인정보 동의, A/B 테스트 기준을 포함해 설계해야 한다.

| 데이터·개인정보 통제 확인 | 동의, 목적 제한, 최소 수집, 삭제권 | 데이터 수집 확대만 강조 |

## Ⅰ. 개요 및 필요성

- 개요: 초개인화 서비스는 개인별 맥락 기반 경험 제공 서비스이다.
- 배경: 사용자의 행동 데이터와 실시간 상황을 반영하면 추천, 메시지, UI를 개인 단위로 바꿀 수 있다.
- 필요성: 개인정보 동의, 목적 제한, 추천 품질 지표를 함께 관리해 서비스 신뢰와 규제 대응을 확보해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User Event -> CDP/Profile -> Feature Store -> Recommendation/Ranking
           -> Decision API -> Channel(App/Web/Push) -> Experiment/Feedback
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 이벤트 수집 | 클릭, 구매, 검색, 위치, 디바이스 이벤트 수집 | 동의 상태 확인 필요 |
| CDP/프로필 | 고객 식별, 선호, 세그먼트, consent 관리 | ID 해석과 삭제 요청 처리 |
| 추천·랭킹 모델 | 후보 생성, 점수화, next best action 선택 | 편향·필터 버블 점검 |
| 실험 플랫폼 | A/B 테스트, uplift, 장기 지표 측정 | 실험군 오염 방지 |

> 요약: 초개인화는 이벤트, 프로필, 특징, 추천, 실험 피드백이 순환하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
동의 확인 -> 이벤트 수집 -> 프로필/특징 갱신 -> 후보 생성
-> 랭킹/정책 필터 -> 채널 노출 -> 반응 측정 -> 모델 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 동의와 목적 확인 | consent 없는 데이터 제외 |
| 2 | 실시간 특징 갱신 | feature freshness 5분 이하 |
| 3 | 추천·랭킹 수행 | CTR, CVR, diversity 측정 |
| 4 | 실험과 피드백 | uplift, churn, 삭제 요청 처리 |

> 요약: 초개인화는 동의 확인 후 개인별 특징을 갱신하고 실험으로 효과와 부작용을 검증한다.

> 요약: 초개인화 성과는 전환율과 API 지연, 개인정보 처리 SLA를 함께 본다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 데이터 기반: CMP로 동의 상태를 관리하고 CDP, Feature Store, 삭제 요청 자동화 파이프라인을 구축
2. 모델 운영: 후보 생성+랭킹 2단 구조, diversity 제약, p95 decision API 100ms 이하 SLO 설정
3. 실험·감사: A/B 테스트로 CVR uplift 5% 이상 검증, 그룹별 편차와 개인정보 처리 로그를 월 단위 점검

**결론 (2줄):**
- 기술사 판단: 단순 캠페인은 세그먼트 개인화, 실시간 추천·채널 최적화가 핵심이면 초개인화를 선택함
- 향후 방향: 초개인화는 CDP, Feature Store, 생성형 AI, Privacy Tech가 결합된 실시간 경험 플랫폼으로 발전함
