## Ⅰ. 개요
- 대상 OS, 성능 요구사항, 개발 예산에 따라 최적의 앱 구현 방식을 선택하는 전략임
- 단일 코드 기반의 효율성과 기기 성능 활용 사이의 트레이드오프가 핵심임
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 방식별 장단점 비교, 웹뷰(WebView), 하이브리드 vs 프로그레시브 웹 | 기성복(웹) vs 맞춤복(네이티브) |

## Ⅱ. 구성요소
- 구현 기술 스택 및 실행 환경에 따라 3가지로 분류됨
[Native: OS 종속] <-> [Hybrid: Web + Native Wrapper] <-> [Web: Browser]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 네이티브 | Java/Kotlin(AOS), Swift(iOS)로 OS 기능을 직접 활용 | 현지인 수준의 유창한 대화 |
| 모바일 웹 | HTML5 기반으로 브라우저를 통해 실행 (PWA로 진화) | 통역기를 통한 제한적 소통 |
| 하이브리드 | 웹 기술로 개발 후 네이티브 컨테이너로 감싸 앱스토어 배포 | 외국인이지만 현지 옷을 입음 |
> 요약: 성능과 기기 제어가 중요하면 네이티브, 생산성과 유지보수가 우선이면 웹/하이브리드임

## Ⅲ. 절차
- 방식 선정을 위한 의사결정 및 개발 흐름임
[요구사항 분석] -> [개발 방식 선정] -> [코드 구현] -> [테스트 및 스토어 등록]
- 4단계 설명
1) 제약 사항 확인: 카메라, 센서 등 하드웨어 접근 빈도 및 성능 목표 설정함
2) 멀티 플랫폼 전략: 단일 코드베이스(Cross-platform) 사용 여부를 결정함
3) 프레임워크 적용: React Native, Flutter(하이브리드/크로스) 등 도구 선정함
4) 성능 최적화: 네이티브 브릿지 오버헤드 감소 및 리소스 경량화 작업 수행함
> 요약: 비즈니스 목적과 자원에 최적화된 앱 아키텍처를 수립함

## Ⅳ. 문제점
- 하이브리드 앱은 네이티브 대비 실행 속도가 느리고 UI 반응성이 떨어짐 (원인: 웹뷰 한계)
- 네이티브 앱은 OS별 별도 개발로 인해 비용이 중복 발생하고 업데이트가 느림 (원인: 파편화)

## Ⅴ. 개선방안
- (단기) 성능이 핵심인 부분만 네이티브로 구현하는 부분 하이브리드 방식 적용함
- (중기) 고성능 크로스 플랫폼 도구(Flutter 등)를 활용하여 생산성과 성능 동시 확보함
- (장기) 설치 없이 앱 수준 경험을 주는 PWA(Progressive Web App) 기술 고도화함

## Ⅵ. 전망
- 하드웨어 성능 상향으로 네이티브와 크로스 플랫폼 간의 체감 격차는 점차 줄어들 것임
- 향후 '슈퍼 앱(Super App)' 플랫폼 내의 미니 앱 생태계가 주류 개발 모델이 될 것임
