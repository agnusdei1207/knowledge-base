## Ⅰ. 개요
- 네트워크 상의 이기종 시스템 간 상호운용성을 보장하기 위한 XML 기반 웹 통신 표준임
- 서비스의 발견(UDDI), 기술(WSDL), 호출(SOAP) 체계로 구성됨
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 3대 표준의 역할, SOAP 메시지 구조, REST와의 차이 | 전화번호부(UDDI) - 광고(WSDL) - 통화(SOAP) |

## Ⅱ. 구성요소
- 서비스 제공자, 사용자, 브로커 간의 삼각 관계 모델임
[사용자] --(WSDL 조회)--> [UDDI: 브로커]
   |                      ^
   +---(SOAP 호출)-------> [제공자]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| SOAP | XML 기반의 메시지 교환 프로토콜 (Envelope/Header/Body) | 규격화된 봉투와 편지 |
| WSDL | 서비스의 위치, 제공 기능, 데이터 형식을 기술한 XML 파일 | 제품 설명서 |
| UDDI | 비즈니스 업체와 서비스를 등록하고 검색하는 저장소 | 114 전화번호부 |
> 요약: 신뢰성 있는 전송과 엄격한 인터페이스 정의를 통한 엔터프라이즈 통신 표준임

## Ⅲ. 절차
- 웹 서비스의 등록 및 활용 프로세스임
[서비스 기술] -> [UDDI 등록] -> [검색 및 바인딩] -> [SOAP 통신]
- 4단계 설명
1) WSDL 생성: 제공할 인터페이스를 XML 명세서로 작성함
2) 서비스 배포: UDDI 레지스트리에 업체 정보와 서비스 위치를 등록함
3) 클라이언트 프록시 생성: 사용자는 WSDL을 다운로드하여 호출 코드를 자동 생성함
4) 메시지 교환: HTTP/SMTP 등의 프로토콜 위에서 SOAP 메시지를 주고받음
> 요약: 복잡한 통신 규약을 자동화하여 서비스 간 동적 결합을 지원함

## Ⅳ. 문제점
- XML 파싱에 따른 과도한 오버헤드로 인해 응답 속도가 느림 (원인: 데이터 비대화)
- 표준 규격이 너무 방대하여 구현 복잡도가 높고 유연성이 떨어짐 (원인: 과잉 설계)

## Ⅴ. 개선방안
- (단기) 성능이 중요한 구간에서는 경량 포맷인 JSON 기반의 REST API로 전환함
- (중기) 보안(WS-Security) 및 신뢰성(WS-Reliability) 요구 시에만 선별적 SOAP 사용함
- (장기) 메타데이터 기반의 자동 연동 기능을 강화한 gRPC 및 오픈 API 체계 고도화함

## Ⅵ. 전망
- 공공/금융의 기간계 연동에는 여전히 표준성 기반으로 유지될 것임
- 향후 AI 서비스의 명세를 정의하는 'AI 서비스 카탈로그' 표준으로 개념이 확장될 전망임
