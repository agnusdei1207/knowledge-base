## 미리 알고가기

- 화이트박스 테스트는 내부 구조와 경로를 기준으로 검증함
- 블랙박스 테스트는 내부 구현을 보지 않고 입력과 출력 기준으로 검증함
- 둘은 대체 관계가 아니라 서로 다른 위험을 담당함

## Ⅰ. 개요

- **정의/개념**: 화이트박스 테스트는 코드 구조와 제어 흐름과 조건 분기를 기준으로 내부 경로를 검증하는 방식이고, 블랙박스 테스트는 구현 세부를 숨긴 채 요구사항과 입력·출력 행위를 기준으로 외부 동작을 검증하는 방식임
- **배경/필요성**: 내부 로직 결함과 요구 해석 오류는 서로 다른 방식으로 드러나므로, 하나의 테스트 관점만으로는 품질 위험을 충분히 줄이기 어렵다

## Ⅱ. 특징

- 화이트박스는 로직 누락과 경로 미실행을 찾는 데 강함
- 블랙박스는 기능 요구와 사용 시나리오 검증에 강함
- 화이트박스만 쓰면 요구 미스매치를 놓치기 쉽고 블랙박스만 쓰면 내부 취약 경로를 놓치기 쉬움
- 테스트 수준과 대상 모듈 특성에 따라 비중이 달라져야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 화이트박스 테스트 | 블랙박스 테스트 |
|:---|:---|:---|
| 기준 정보 | 내부 코드 구조 | 요구와 입출력 명세 |
| 장점 | 경로와 조건 검증 가능 | 사용자 관점 검증 가능 |
| 한계 | 구현 의존성 큼 | 경로 누락 탐지 약함 |
| 적합 단계 | 단위와 구조 중심 테스트 | 통합과 시스템과 인수 테스트 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Structural Path View | 제어 흐름과 분기와 조건을 분석해 코드 내부 위험 지점을 드러냄 |
| Behavioral Spec View | 사용 시나리오와 요구 명세를 기반으로 기대 결과를 검증함 |
| Test Case Derivation Rule | 구조 기반과 요구 기반으로 케이스 도출 기준을 달리해 위험 누락을 줄임 |
| Combined Coverage Strategy | 두 관점을 함께 운영해 기능과 로직 결함을 균형 있게 잡음 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대상 분석      | --> | 케이스 도출    | --> | 실행/실패 관찰 | --> | 공백 보완      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대상 분석**: 구조 기반인지 요구 기반인지 관점을 정함
2. **케이스 도출**: 경로나 시나리오를 기준으로 테스트를 설계함
3. **실행 및 실패 관찰**: 결함 위치나 요구 위반을 확인함
4. **공백 보완**: 다른 관점 테스트로 누락 영역을 채움

## Ⅵ. 문제점 및 해결 방안

1. 문제: 화이트박스 테스트가 구현 세부에 과도하게 묶이면 리팩터링 때 유지비만 크게 늘 수 있음
   - 해결방안: 핵심 경로 중심으로 구조 테스트를 설계하고 brittle test ratio와 path defect catch rate로 검증함
2. 문제: 블랙박스 테스트만 수행하면 코드 내부 희귀 분기와 오류 경로가 장기간 미검증 상태로 남을 수 있음
   - 해결방안: 구조 기반 테스트를 병행하고 uncovered branch ratio와 defect escape rate로 검증함
3. 문제: 두 방식을 중복 없이 나누지 않으면 테스트 수만 늘고 위험 대비 효과는 낮아질 수 있음
   - 해결방안: 테스트 목적별 책임을 분리하고 test overlap ratio와 suite efficiency score로 검증함

## Ⅶ. 적용 사례

- 핵심 계산 모듈에서는 화이트박스 테스트를 강화하고 확인 지표는 path defect catch rate와 brittle test ratio임
- 사용자 업무 흐름 검증에서는 블랙박스 테스트를 운영하고 확인 지표는 acceptance coverage와 defect escape rate임
- 품질 조직에서는 두 관점의 책임을 분리하고 확인 지표는 uncovered branch ratio와 suite efficiency score임

## Ⅷ. 결론

화이트박스와 블랙박스의 선택은 어느 쪽이 더 낫냐가 아니라 내부 결함과 요구 결함을 각각 어떤 관점으로 잡아낼지 역할을 나누는 문제임.
