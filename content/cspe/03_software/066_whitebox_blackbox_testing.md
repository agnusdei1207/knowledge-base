## 미리 알고가기

- 화이트박스 테스트는 내부 코드 구조와 분기를 기준으로 검증하는 방식임
- 블랙박스 테스트는 내부 구현을 보지 않고 입력과 출력과 요구 기준으로 검증하는 방식임
- 두 방식은 대체 관계가 아니라 서로 다른 위험을 맡는 보완 관계임

## 작성 근거(검토용)

- 화이트박스·블랙박스 테스트는 기준 정보, 발견 결함, 한계, 적용 수준을 핵심 비교축으로 선정함
- 구성은 구조 관점과 행위 관점의 테스트 사례 도출 기준을 중심으로 제시함
- 실무 판단은 미실행 분기율, 경로 결함 탐지율, 요구 시나리오 충족률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 화이트박스 테스트는 내부 제어 흐름·분기·경로를, 블랙박스 테스트는 요구사항·입출력·업무 시나리오를 검증하는 방식임
- **배경/필요성**: 내부 로직 결함과 요구 불일치는 서로 다른 관점에서 발견되므로 구조 기반과 행위 기반 검증이 모두 필요함

## Ⅱ. 특징

- 화이트박스는 로직 누락과 실행 빈도가 낮은 분기 오류를 탐지함
- 블랙박스는 입력·출력·업무 시나리오를 기준으로 기능 요구 충족 여부를 검증함
- 화이트박스는 요구 명세 오류를 직접 검증하지 않고 블랙박스는 내부 경로 실행 여부를 측정하지 않음
- 테스트 수준과 모듈 특성에 따라 두 방식의 비중이 달라져야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 화이트박스 테스트 | 블랙박스 테스트 |
|:---|:---|:---|
| 기준 정보 | 내부 코드 구조와 분기와 경로를 기준으로 삼음 | 요구사항과 입출력과 업무 시나리오를 기준으로 삼음 |
| 탐지 대상 | 미실행 로직과 조건 누락 | 사용자 기능 오류와 요구 불일치 |
| 구조상 한계 | 구현 의존이 커서 구조 변경 때 유지비가 늘 수 있음 | 내부 희귀 경로나 숨은 오류 처리 흐름은 놓칠 수 있음 |
| 대표 수준 | 단위 테스트·분기·오류 처리 경로 검증 | 통합·시스템·인수 테스트의 계약·시나리오 검증 |

> 요약: 내부 분기·경로 결함은 화이트박스, 요구·입출력 오류는 블랙박스 테스트로 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 구조 관점 | 제어 흐름과 분기와 조건을 분석해 코드 내부 위험 지점을 드러냄 |
| 행위 관점 | 사용 시나리오와 요구 명세를 기준으로 기대 결과를 검증함 |
| 테스트 케이스 도출 기준 | 코드 경로와 요구 시나리오에서 각각 테스트 사례를 도출함 |
| 결합 운영 전략 | 구조 기반 사례와 행위 기반 사례를 함께 실행함 |

> 요약: 코드 구조에서 경로 사례를, 요구 명세에서 행위 사례를 도출해 로직과 기능 결함을 함께 검증함.

## Ⅵ. 실무 사례

1. 계산·권한 모듈은 화이트박스 테스트로 분기를 검증하고 미실행 분기율·경로 결함 탐지율을 확인함
2. 사용자 업무 흐름은 블랙박스 테스트로 검증하고 시나리오 충족률·운영 유출 결함률을 확인함

## Ⅶ. 결론

화이트박스와 블랙박스 테스트는 내부 구조 결함과 외부 행위 오류를 서로 다른 관점에서 보완 검증함
