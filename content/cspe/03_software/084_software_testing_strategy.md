## Ⅰ. 개요
- **정의**: 프로젝트 목표·위험 수준에 따라 테스트 범위·수준·자동화 비율을 체계적으로 결정하는 계획
- **배경/필요성**: 무한한 테스트 조합 중 한정된 자원으로 결함 검출 효과를 극대화해야 함
- **비유**: 건물 점검 시 기둥(핵심)부터, 그다음 벽·창문 순으로 우선순위를 정하는 점검 계획표

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 테스트 수준·유형 분류 체계 이해 | 테스트 피라미드(단위 > 통합 > E2E) 비율 | V-모델 매핑과 위험 기반 우선순위를 언급할 것 |

> 요약: 한정 자원으로 결함 검출 효과를 극대화하기 위한 테스트 계획 체계임

## Ⅱ. 구성요소
```text
        /  E2E (소량)  \
       / Integration    \
      /   Unit (대량)    \
     +-------------------+
     |  Test Pyramid      |
     +-------------------+
Strategy = Pyramid + Risk Matrix + Automation Policy
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Test Pyramid | 단위-통합-E2E 비율을 계층화한 테스트 구성 모델 | 피라미드 식단표 |
| Risk Matrix | 모듈별 장애 영향도·발생 확률로 테스트 우선순위를 결정하는 표 | 위험 지도 |
| Automation Policy | 반복·회귀 테스트의 자동화 범위·도구를 정의하는 정책 | 자동 세차 vs 손세차 기준 |

> 요약: 피라미드-위험 매트릭스-자동화 정책 3요소로 전략을 구성함

## Ⅲ. 절차
```text
위험 분석 --> 테스트 수준 설계 --> 자동화 범위 결정 --> 실행·피드백
```
- 1단계: 위험 분석—모듈별 결함 영향도·변경 빈도를 평가해 우선순위 도출
- 2단계: 테스트 수준 설계—단위·통합·E2E 비율을 피라미드 원칙에 따라 배분
- 3단계: 자동화 범위 결정—반복 빈도가 높은 회귀 테스트를 자동화 대상으로 선정
- 4단계: 실행·피드백—CI 파이프라인에서 테스트를 실행하고 커버리지·결함률을 모니터링

> 요약: 위험 분석-수준 설계-자동화-실행 4단계로 전략을 수립·운영함

## Ⅳ. 문제점
- 피라미드 역전: E2E 비중이 과도하면 실행 시간이 길어져 CI 병목이 발생함
- 위험 평가 편향: 경험 기반 주관 평가 시 신규 모듈의 위험을 과소 추정할 수 있음
- 자동화 유지 비용: UI 변경에 취약한 E2E 스크립트가 빈번히 깨져 유지 공수가 증가함

> 요약: 피라미드 역전, 평가 편향, 자동화 유지 비용이 전략 실효성을 저해함

## Ⅴ. 개선방안
1. 단기: 단위 테스트 커버리지 임계치(예: 80 %)를 CI 게이트로 강제해 피라미드 비율 유지
2. 중기: 결함 이력·코드 변경량 데이터로 위험 점수를 정량화해 편향 감소
3. 장기: 테스트 자동 생성·자가 치유(Self-Healing) 프레임워크 도입으로 유지 비용 절감

> 요약: CI 게이트-정량 위험 평가-자가 치유 순으로 전략을 고도화함

## Ⅵ. 전망
- 발전 방향: AI 기반 테스트 케이스 자동 생성·우선순위 추천으로 전략 수립 자동화
- 기술사적 판단: Shift-Left 테스팅과 결합해 개발 초기 단계에서 결함을 검출하는 추세임
- 기술사 제언: 테스트 전략을 아키텍처 의사결정 기록(ADR)과 연계해 관리할 필요
