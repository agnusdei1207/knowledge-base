## Ⅰ. 개요
- 정의: 자주 발생하는 설계 문제에 대한 검증된 해결책을 유형별로 정리한 목록
- 배경: 설계 경험의 공유를 통한 개발 생산성 향상 및 코드 품질 표준화 필요
- 출제 의도: 주요 패턴(GoF 등)의 분류 체계 및 활용 목적 이해 측정

## Ⅱ. 구성요소
- 구조도
  [Design Pattern Catalog]
  +-- [생성(Creational)]: 객체 생성 로직 은닉
  +-- [구조(Structural)]: 클래스/객체 조합 구성
  +-- [행위(Behavioral)]: 객체 간 상호작용 정의

- 구성요소 표
| 분류 | 대표 패턴 | 설명 |
| :--- | :--- | :--- |
| 생성 | Singleton, Factory Method | 객체 생성의 유연성 확보 |
| 구조 | Adapter, Decorator | 구조 변경 없이 기능 확장 |
| 행위 | Strategy, Observer | 알고리즘 및 상태 변경 대응 |
> 요약: 반복되는 설계 문제를 생성·구조·행위 유형으로 분류하고 적용 조건과 결과를 함께 기록함

## Ⅲ. 절차
- 흐름도
  문제 식별 -> 패턴 검색 -> 컨텍스트 적용 -> 구현 및 검증
- 4단계 설명
1. 문제 식별: 설계 과정에서 반복되는 구조적/기능적 난제 발견
2. 패턴 검색: 카탈로그 내 유사한 문제 상황을 해결하는 패턴 탐색
3. 컨텍스트 적용: 현재 시스템의 제약 사항을 고려하여 패턴 변형 설계
4. 구현 및 검증: 선택한 패턴을 코드로 구현하고 의도대로 동작하는지 테스트
> 요약: 문제의 맥락과 제약을 패턴 적용 조건과 비교하고 변형 결과를 구현·검증함

## Ⅳ. 문제점
- 패턴의 과도한 적용(Over-Engineering)으로 인한 시스템 복잡도 불필요 증가
- 패턴 명칭만 사용하고 실제 의도와 다르게 구현하여 유지보수 혼선 초래

## Ⅴ. 개선방안
- 문제의 본질을 먼저 파악하고, 패턴 적용의 득실을 면밀히 검토 후 도입
- 팀 내 패턴 활용 가이드라인 수립 및 지속적인 코드 리뷰를 통한 정합성 확보

## Ⅵ. 전망
- 클라우드 패턴, MSA 패턴 등 아키텍처 수준의 카탈로그화 영역 확장
- CSF: 패턴 언어(Pattern Language)로서의 소통 도구 활용 및 도메인 최적화
