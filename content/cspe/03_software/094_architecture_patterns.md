## Ⅰ. 개요
- 시스템의 전체적인 구조를 정의하는 고수준의 설계 템플릿임.
- 복잡한 시스템을 분할하여 관리하고 유지보수성을 높이는 것이 주 목적임.
- 출제 의도: 레이어드, 파이프-필터, MVC, MSA 등 주요 아키텍처 비교 분석.

## Ⅱ. 구성요소
- 주요 아키텍처 패턴
[Presentation] -> [Business] -> [Data] | [Filter] -> [Pipe] -> [Filter]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Layered | 계층별로 책임을 분리하고 하위 계층에만 의존함 | 아파트 층별 구조 |
| Pipe-Filter | 데이터를 순차적으로 처리하는 필터들의 연결 | 정수기 필터 라인 |
| Broker | 분산 환경에서 컴포넌트 간 통신을 중재함 | 공인중개사 |
> 요약: 시스템의 거시적 구조를 결정하여 개발 표준을 제시함.

## Ⅲ. 절차
- 레이어드 아키텍처 설계 단계
[Layer Definition] -> [Interface Setup] -> [Dependency Rule] -> [Deployment]

1. 계층 정의: UI, 서비스, 도메인, 인프라 등 논리적 경계를 설정함.
2. 인터페이스 설계: 계층 간 소통을 위한 표준 API를 정의함.
3. 의존성 제약: 하위 계층은 상위를 알 수 없도록 방향성을 강제함.
4. 구현 및 배치: 각 계층을 모듈화하여 독립적으로 개발 및 배포함.
> 요약: 관심사 분리(SoC)를 통해 계층별 독립적 진화를 지원함.

## Ⅳ. 문제점
- 계층 간 불필요한 데이터 변환 오버헤드 및 특정 계층의 비대화(Fat Layer).

## Ⅴ. 개선방안
- 도메인 주도 설계(DDD) 기반의 바운디드 컨텍스트(Bounded Context) 적용.

## Ⅵ. 전망
- 클라우드 네이티브를 위한 서버리스 및 이벤트 기반 아키텍처(EDA) 채택 급증.
- AI 워크로드를 효율적으로 처리하기 위한 가속기 중심 아키텍처 패턴 대두.
