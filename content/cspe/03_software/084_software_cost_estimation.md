## 미리 알고가기

- 소프트웨어 대가산정은 개발 범위와 품질 요구와 인력 단가를 기반으로 비용을 추정하는 활동임
- 기능 규모와 난도와 비기능 요구를 함께 봐야 한다
- 견적은 숫자 산출보다 가정 관리가 더 중요하다

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 대가산정은 개발 대상의 기능 규모와 기술 난도와 품질 요구와 기간과 인력 조건을 종합해 합리적인 개발 비용과 유지보수 비용을 계산하는 활동임
- **배경/필요성**: 비용을 과소 산정하면 일정과 품질이 무너지고 과대 산정하면 수주 경쟁력과 투자 효율이 떨어지므로, 체계적 비용 추정이 필요함

## Ⅱ. 특징

- 기능 규모와 기술 복잡도와 조직 생산성을 함께 고려해야 한다
- 초기 추정은 불확실성이 크므로 가정 관리가 중요하다
- 비기능 요구와 운영 전환 비용을 빼면 실제 비용이 과소화되기 쉽다
- 추정 결과보다 추정 근거와 변경 관리 체계가 더 중요할 때가 많다

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 경험 추정 | 체계적 대가산정 |
|:---|:---|:---|
| 근거 | 개인 경험 중심 | 규모·보정·단가 근거 명시 |
| 장점 | 빠른 대응 | 추적성과 설명력 높음 |
| 한계 | 편차와 재현성 부족 | 입력 자료와 보정 노력 필요 |
| 적합 환경 | 예비 검토 | 계약·투자 의사결정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Scope Baseline | 어떤 기능과 산출물이 비용 대상인지 명확히 해 견적 경계를 정함 |
| Size and Complexity Input | 기능 규모와 기술 난도가 총 노력 추정의 핵심 입력이 된다 |
| Unit Cost and Productivity | 인력 단가와 조직 생산성이 비용 환산의 기준이 된다 |
| Risk and Contingency | 변경과 불확실성을 반영해 실제 계약과 수행 가능성을 높인다 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 범위 정의      | --> | 규모/난도 산정 | --> | 비용 환산      | --> | 위험 보정/합의 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **범위 정의**: 비용 산정 대상 범위를 고정함
2. **규모와 난도 산정**: 기능과 비기능과 기술 복잡도를 평가함
3. **비용 환산**: 생산성과 단가를 적용해 비용을 계산함
4. **위험 보정과 합의**: 불확실성 보정과 변경 기준을 명시함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 범위 정의가 약하면 견적이 기능 추가 때마다 흔들려 계약 분쟁으로 이어질 수 있음
   - 해결방안: scope baseline을 명확히 하고 change request ratio와 contract dispute count로 검증함
2. 문제: 비기능 요구와 전환 비용을 빼고 계산하면 수행 단계에서 비용 초과가 발생할 수 있음
   - 해결방안: nonfunctional cost 항목을 포함하고 estimate completeness score와 cost overrun rate로 검증함
3. 문제: 과거 생산성 데이터 없이 단가만 곱하면 조직 현실과 동떨어진 예측이 나올 수 있음
   - 해결방안: historical benchmark를 구축하고 productivity baseline quality와 forecast error로 검증함

## Ⅶ. 적용 사례

- 공공 SW 사업 견적에서는 대가산정을 수행하고, estimate completeness score와 contract dispute count로 결과를 확인함
- 기업 내부 투자 심사에서는 위험 보정을 반영하고, cost overrun rate와 forecast error로 결과를 확인함
- 조직 견적 체계 개선에서는 생산성 기준선을 축적하고, productivity baseline quality와 change request ratio로 결과를 확인함

## Ⅷ. 결론

소프트웨어 대가산정의 핵심은 숫자를 만드는 데 있지 않고 범위와 가정과 위험을 투명하게 드러내 실제 수행 가능한 계약과 계획을 만드는 데 있음.
