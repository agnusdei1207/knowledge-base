## Ⅰ. 개요
- **정의**: 조직 내 데이터 자산의 메타데이터를 수집·분류·검색 가능하게 관리하는 체계
- **배경/필요성**: 데이터 자산이 증가할수록 어떤 데이터가 어디에 있는지 파악이 어려워 탐색 비용이 증가함
- **비유**: 도서관의 도서 검색 시스템과 같음 — 책 내용이 아닌 위치와 분류를 관리함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 거버넌스 도구 이해 | 메타데이터 자동 수집, 태깅, 검색 기능 | 데이터 웨어하우스와 카탈로그의 역할 차이 |

> 요약: 메타데이터 기반으로 데이터 자산을 검색·탐색 가능하게 하는 인벤토리임

## Ⅱ. 구성요소
```text
[데이터 소스] --> [크롤러/수집기] --> [메타데이터 저장소]
                                          |
                                     [검색 엔진]
                                          |
                                     [태깅/분류]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 크롤러 | 데이터 소스에서 스키마·통계 메타데이터를 자동 수집하는 모듈 | 도서관 신간 등록 담당 |
| 메타데이터 저장소 | 기술·비즈니스·운영 메타데이터를 통합 보관하는 저장소 | 서지 카드 보관함 |
| 검색 엔진 | 키워드·태그 기반으로 데이터 자산을 탐색하는 기능 | 도서 검색 단말 |
| 태깅/분류 | 비즈니스 용어·도메인 태그를 부여하여 탐색성을 높이는 기능 | 분류 번호 부여 |

> 요약: 크롤러가 메타데이터를 수집하고 검색·태깅으로 탐색성을 제공하는 구조임

## Ⅲ. 절차
```text
소스 연결 --> 메타데이터 수집 --> 태깅/분류 --> 검색/활용
```
- 1단계: 소스 연결 — DB·스토리지·API 등 데이터 소스를 카탈로그에 등록함
- 2단계: 메타데이터 수집 — 크롤러가 스키마·컬럼·통계 정보를 자동 추출함
- 3단계: 태깅/분류 — 비즈니스 용어·도메인·소유자 정보를 태그로 부여함
- 4단계: 검색/활용 — 사용자가 키워드로 데이터 자산을 탐색하고 활용함

> 요약: 소스 등록-수집-태깅-검색의 4단계로 데이터 자산 탐색을 지원함

## Ⅳ. 문제점
- 메타데이터 부실: 크롤러 미지원 소스는 수동 등록 필요 — 등록 누락 발생
- 태그 비일관성: 부서별 상이한 용어 사용 — 검색 정확도 저하
- 최신성 미보장: 스키마 변경 시 카탈로그 갱신 지연 — 정보 불일치

> 요약: 메타데이터 누락, 태그 비일관, 최신성 미보장이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 커스텀 커넥터 개발로 미지원 소스 자동 수집 범위 확대
2. 중기: 비즈니스 용어 사전(Glossary) 수립으로 태그 표준화
3. 장기: 스키마 변경 이벤트 기반 실시간 메타데이터 갱신 체계 구축

> 요약: 수집 확대, 용어 표준화, 실시간 갱신으로 카탈로그 신뢰도를 확보할 필요

## Ⅵ. 전망
- 발전 방향: AI 기반 자동 태깅 및 데이터 추천으로 셀프서비스 분석 지원 강화
- 기술사적 판단: 데이터 리니지(154 참조)와 카탈로그의 통합이 가속화될 전망
- 기술사 제언: 카탈로그를 데이터 거버넌스 허브로 위치시켜 접근 통제·품질 관리와 연계할 필요
