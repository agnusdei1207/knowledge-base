## Ⅰ. 개요
- 정의: 빌드된 산출물을 운영 환경에 자동으로 적용하고 전환하는 기술
- 배경: 잦은 배포 요구에 대응하고, 배포 시 발생하는 서비스 중단 시간을 최소화 필요
- 출제 의도: 배포 자동화의 이점 및 블루-그린(Blue-Green) 방식의 메커니즘 이해

## Ⅱ. 구성요소
- 구조도
  [Blue (Old)] --(Standby)--+
                            |-- [Load Balancer] --> [Traffic]
  [Green (New)] --(Active)--+

- 구성요소 표
| 구성요소 | 설명 | 역할 |
| :--- | :--- | :--- |
| Blue 환경 | 현재 서비스 중인 안정된 버전의 환경 | 기존 서버 |
| Green 환경 | 신규 버전이 배포되어 테스트를 마친 환경 | 신규 서버 |
| 라우터/L4 | 트래픽을 Blue에서 Green으로 일괄 전환 | 스위치(Switch) |
> 요약: 동일한 규모의 두 환경을 준비하여 무중단 배포 및 즉각 롤백 실현

## Ⅲ. 절차
- 흐름도
  Green 환경 구성 -> 신규 배포/테스트 -> 트래픽 전환 -> Blue 환경 대기
- 4단계 설명
1. Green 환경 구성: 운영(Blue)과 동일한 사양의 별도 환경 준비
2. 신규 배포/테스트: Green 환경에 신규 코드를 배포하고 기능/성능 최종 검증
3. 트래픽 전환: 로드밸런서 설정을 변경하여 모든 트래픽을 Green으로 즉시 유도
4. Blue 환경 대기: 이상 없을 시 Blue는 다음 배포를 위해 대기(또는 자원 회수)
> 요약: 환경 분리를 통해 배포 리스크를 격리하고 서비스 가용성 극대화

## Ⅳ. 문제점
- 운영 환경을 이중으로 유지해야 하므로 인프라 자원 비용이 2배로 발생
- 구버전(Blue)과 신버전(Green) 간의 데이터베이스 스키마 불일치로 인한 오류 가능성

## Ⅴ. 개선방안
- 클라우드 환경의 유연성을 활용하여 배포 시점에만 임시 자원 할당 (비용 절감)
- DB 변경 시 하위 호환성을 고려한 다단계 마이그레이션(Expand/Contract) 전략 적용

## Ⅵ. 전망
- 서비스 메시(Service Mesh) 기반의 세밀한 트래픽 제어를 통한 배포 고도화
- CSF: 배포 파이프라인의 가시성 확보 및 장애 발생 시 자동 롤백 체계 구축
