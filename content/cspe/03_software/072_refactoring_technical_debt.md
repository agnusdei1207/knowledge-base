## 미리 알고가기

- 리팩터링은 외부 동작을 유지한 채 내부 구조를 개선하는 활동임
- 기술부채는 단기 납기를 위해 미룬 설계·품질 문제로 미래 변경 비용이 커진 상태임
- 보호 테스트는 구조를 바꿔도 기존 동작이 유지되는지 확인하는 회귀 방지 테스트임

## 작성 근거(검토용)

- 리팩터링·기술부채는 성격, 목적, 관리 결과, 실패 위험을 핵심 비교축으로 선정함
- 구성은 동작 보호망, 부채 목록, 영향 지표, 개선 시점의 관계를 중심으로 제시함
- 실무 판단은 기능 반영시간, 반복 결함률, 회귀 결함 수로 구체화함

## Ⅰ. 개요

- **정의/개념**: 리팩터링은 외부 동작을 유지하며 내부 구조를 개선하는 활동이고, 기술부채는 미룬 설계·품질 문제로 변경 비용이 누적된 상태임
- **배경/필요성**: 모든 부채를 즉시 해소할 수 없으므로 변경 빈도·영향도·상환 비용에 따라 리팩터링 우선순위를 정할 기준이 필요함

## Ⅱ. 특징

- 리팩터링은 외부 동작을 유지하며 중복·결합·복잡도를 줄이는 활동임
- 기술부채는 변경이 반복될수록 수정 범위와 회귀 결함을 늘림
- 테스트 보호망 없이 리팩터링하면 회귀 위험이 커짐
- 변경 범위가 큰 일괄 리팩터링은 기능 개발 일정과 회귀 검증 범위를 함께 늘림

## Ⅲ. 종류 및 비교

| 판단 기준 | 리팩터링 | 기술부채 |
|:---|:---|:---|
| 성격 | 구조를 개선하는 실행 활동임 | 미래 변경 비용을 키우는 누적 상태임 |
| 직접 목적 | 가독성과 변경 용이성과 테스트 가능성을 높임 | 어떤 비용과 위험이 쌓였는지 인식하고 관리하게 함 |
| 관리 결과 | 중복·결합·복잡도를 줄이고 외부 동작 유지 | 부채 원인·영향·상환 비용을 기록해 우선순위 결정 |
| 주된 한계 | 테스트 없이 수행하면 회귀 결함을 만들 수 있음 | 측정과 기록이 없으면 추상적 불만으로만 남기 쉬움 |

> 요약: 기술부채는 미래 변경 비용이 누적된 상태이고 리팩터링은 외부 동작을 유지하며 이를 줄이는 활동임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 동작 보호망 | 자동 테스트가 있어야 리팩터링의 회귀 위험을 통제할 수 있음 |
| 부채 항목 목록 | 부채 원인·영향·상환 비용을 기록해 우선순위 근거를 제공함 |
| 영향 지표 | 변경 속도와 결함률과 복잡도를 함께 봐 부채 비용을 설명하게 함 |
| 리팩터링 투입 시점 | 구조 개선을 반영할 스프린트·릴리스 계획을 정함 |

> 요약: 부채 목록과 영향 지표로 우선순위를 정하고 동작 보호망을 확보한 뒤 리팩터링을 수행함.

## Ⅵ. 실무 사례

1. 레거시 핵심 모듈은 부채 항목을 변경 영향도로 정렬하고 기능 반영시간·반복 결함률을 확인함
2. 스프린트 리팩터링은 보호 테스트 후 작은 단위로 수행하고 회귀 결함 수를 확인함

## Ⅶ. 결론

리팩터링은 보호 테스트를 기반으로 기술부채를 줄여 이후 기능 변경의 비용과 결함 위험을 낮춤
