## 미리 알고가기

- 정규화(Normalization): 함수 종속성을 기반으로 릴레이션을 분해하여 데이터 중복과 삽입, 삭제, 갱신 이상을 배제하는 논리 설계 과정임
- 함수 종속성(Functional Dependency, $X \rightarrow Y$): 결정자 $X$의 값이 속성 $Y$의 값을 고유하게 결정하는 데이터베이스 내의 종속 관계임
- 완전 함수 종속(Full Functional Dependency): 속성 $Y$가 복합 결정자 $X$ 전체에만 종속되고, $X$의 임의의 진부분집합에는 종속되지 않는 경우임
- 부분 함수 종속(Partial Functional Dependency): 복합 결정자 $X$의 일부 속성에 속성 $Y$가 종속되는 비정상적 상태임
- 이행적 함수 종속(Transitive Functional Dependency, $X \rightarrow Y$ 이고 $Y \rightarrow Z$ 일 때 $X \rightarrow Z$가 성립): 기본키가 아닌 다른 속성을 거쳐 결정되는 종속 관계임
- BCNF(Boyce-Codd Normal Form): 모든 결정자가 후보키가 되도록 제한하여 3NF의 한계를 개선한 정규형임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 관계형 데이터 모델링의 핵심인 정규화 4단계(1NF~BCNF) 조건과 함수 종속성의 유형을 규명하고, 이상 현상 억제와 조회 성능(Join) 간 조율 기준을 정립하기 위함
- 절 구성 및 전개 흐름 이유: 개요에서 정규화의 정의와 이상 현상 제거 필요성을 소개함. 특징에서 무손실 분해 성질을 강조하고, 비교표에서 1NF부터 BCNF까지의 정규화 요건과 제거 대상을 점층적으로 분석함. 구조 설계에서는 함수 종속 관계와 스키마 분해를 정형화하고, 정규화 흐름의 단계별 검증 절차를 실무 사례와 결부해 서술함
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 본문, 표 헤더·셀, 요약, 결론의 전체 맞춤법 및 한국어 표현 자연스러움을 검사하고 5회 완독을 통과함

## Ⅰ. 개요

- **정의/개념**: 데이터베이스 정규화는 함수 종속성을 기준으로 릴레이션을 무손실 분해하여 데이터 중복성을 배제하고 삽입·삭제·갱신 시 발생하는 이상 현상(Anomaly)을 최소화하는 관계형 논리 설계 기법임
- **배경/필요성**: 동일 사실의 중복 저장으로 인해 갱신 누락이나 정보 모순이 발생하는 위험을 근절하고, 저장 효율과 무결성을 극대화하기 위해 명확한 스키마 분해 규칙이 요구됨

### 쉽게 이해하기 (학습용)
- 하나의 커다란 표에 회원 정보와 주문 정보를 다 구겨 넣었을 때 생기는 오류들을 막기 위해, 주제별로 표를 깔끔하게 쪼개는 정리 작업임

## Ⅱ. 특징

- 결정자와 종속자 간의 함수 종속성($FD$) 분석을 수학적 기반으로 하여 릴레이션을 쪼갬
- 정규화 과정은 반드시 원본 릴레이션으로 복원이 가능한 무손실 조인 분해($Lossless$-$join$ $Decomposition$) 성질을 만족해야 함
- 논리적 무결성이 극대화되는 대신, 여러 테이블을 엮어 조회할 때 조인($Join$) 연산이 늘어나 쿼리 응답 속도가 지연될 수 있음
- 비즈니스 업무 흐름(엔티티 라이프사이클)과 기본키 구조가 확실할 때 비로소 정확한 정규화 결과가 보장됨

### 쉽게 이해하기 (학습용)
- 중복이 사라져서 데이터 수정이 간편해지고 안전해지지만, 원하는 정보를 한눈에 보려면 흩어진 표들을 연결(조인)해야 해서 조회할 때 시간이 더 걸릴 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 1NF | 2NF | 3NF | BCNF |
|:---|:---|:---|:---|:---|
| 정규화 조건 | 속성 값을 관계 모델의 원자값으로 구성 | 복합 후보키 일부에 대한 부분 함수 종속 제거 | 비키 속성 사이 이행 함수 종속 제거 | 모든 비자명 함수 종속의 결정자를 후보키로 제한 |
| 줄이는 문제 | 반복 속성과 다중 값 저장 | 복합키 기반 중복 | 이행 종속에 따른 중복 | 숨은 결정자 때문에 남는 이상 현상 |
| 유의점 | 값 분리만으로 충분하지 않음 | 복합 후보키를 모두 식별해야 함 | 업무 규칙을 잘못 이해하면 의미가 깨질 수 있음 | 분해 후 조인 부담을 함께 검토해야 함 |

> 요약: 1NF는 원자값, 2NF는 부분 종속, 3NF는 이행 종속, BCNF는 후보키가 아닌 결정자 문제를 다룸.

### 쉽게 이해하기 (학습용)
- 칸마다 한 값만 넣기(1단계), 전체 키에만 매달리게 하기(2단계), 징검다리 관계 끊기(3단계), 가짜 보스 결정자 몰아내기(BCNF)로 비교됨

## Ⅳ. 설계 요소 및 구조

```text
+------------------------------------------------------------+
|                       정규화 분석 스키마                   |
+------------------------------------------------------------+
       │                              │
       ▼                              ▼
+──────────────────────+      +──────────────────────+
|   1. 식별 메커니즘   |      |   2. 함수 종속 유형  |
|   - 후보키 식별      |      |   - 부분 함수 종속   |
|   - 결정자 추출      |      |   - 이행 함수 종속   |
+──────────────────────+      +──────────────────────+
       │                              │
       +──────────────┬───────────────+
                      ▼
+────────────────────────────────────────────────────────────+
|                     3. 스키마 분해 및 검증                 |
|   - 무손실 조인 분해 (Lossless-Join)                       |
|   - 종속성 보존 분해 (Dependency Preservation)             |
+------------------------------------------------------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 함수 종속성 ($FD$) | 릴레이션 내에서 어떤 속성 $X$의 값이 속성 $Y$의 값을 유일하게 결정하는 제약조건 |
| 후보키 및 결정자 | 튜플을 고유하게 구별하는 최소 속성 집합이며, 종속을 유도하는 주체 주어 |
| 무손실 조인 분해 | 테이블을 쪼갠 후 자연 조인($\bowtie$)을 했을 때 원래의 튜플들과 완벽히 일치함을 보장하는 수학적 성질 |
| 종속성 보존 규칙 | 원래 릴레이션에 존재하던 함수 종속성 제약이 쪼개진 개별 테이블들에서도 그대로 유지되게 하는 성질 |

> 요약: 함수 종속성과 후보키로 분해 대상을 찾고 무손실 분해·종속 보존으로 결과를 검증함.

### 쉽게 이해하기 (학습용)
- 어떤 속성이 누구에게 매여 있는지(종속성) 파악하여 기준(후보키)대로 찢고, 나중에 다시 합쳐도 원래 그림이 나오는지(무손실) 검사하는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
[요구 엔티티 식별] ── (원시 테이블 구성)
       │
       ▼
[1NF 변환] ── (도메인 원자값 확보, 다중값/반복그룹 제거)
       │
       ▼
[2NF 변환] ── (부분 함수 종속 제거 -> 완전 함수 종속화)
       │
       ▼
[3NF 변환] ── (이행적 함수 종속 제거)
       │
       ▼
[BCNF 변환] ── (후보키가 아닌 결정자 관계의 테이블 분리)
       │
       ▼
[분해 적합성 검증] ── (무손실 조인 및 종속성 보존 체크)
```

1. **종속성 도출 및 1NF 구현**: 속성들이 하나의 원자값($Atomic$ $Value$)만 갖도록 분해하여 기본 릴레이션을 생성함
2. **부분 종속 제거 (2NF)**: 기본키가 복합키인 경우, 기본키 일부 속성에 종속되는 부분 함수 종속 관계를 분리하여 완전 함수 종속으로 전환함
3. **이행 종속 제거 (3NF)**: $X \rightarrow Y \rightarrow Z$ 와 같이 비키 속성을 거쳐 기본키에 간접 종속되는 이행적 관계를 별도 테이블로 분해함
4. **결정자 정돈 (BCNF)**: 모든 비자명 함수 종속에서 결정자가 항상 후보키가 되도록 강제하여 숨겨진 결정자 문제를 배제함
5. **무손실 및 보존성 검증**: 분해된 릴레이션들이 조인 연산을 통해 왜곡 없이 복원되는지($Lossless$-$Join$)와 기존 종속성 규칙이 지켜졌는지 확인함

> 요약: 함수 종속성 위반을 식별해 릴레이션을 분해하고 원래 관계의 무손실 복원 여부를 검증함.

### 쉽게 이해하기 (학습용)
- 한 칸에 여러 개 적힌 칸 찢기(1), 복합키의 절반에만 종속된 열 찢기(2), 기본키가 아닌 열에 얹혀사는 열 찢기(3), 가짜 보스 찢기(BCNF)의 순차적 흐름임

## Ⅵ. 실무 사례

1. 신규 업무 DB는 함수 종속성과 후보키로 정규화하고 무손실 분해 위반 건수·중복 속성 수를 확인함
2. 조회 API DB는 정규 모델을 유지한 채 반정규화 후보를 검증하고 p95 조회 지연·조인 깊이를 확인함

### 쉽게 이해하기 (학습용)
- 주문과 결제는 실수가 없도록 표를 쪼개어 정규화해 쓰고(OLTP), 통계 보고서는 빠른 조회를 위해 일부러 표를 도로 합쳐(반정규화) 사용함

## Ⅶ. 결론

- 데이터베이스 정규화는 관계형 모델의 기본 무결성을 지탱하는 근간 설계 기법이며, 함수 종속성 통제를 통해 삽입/삭제/갱신 이상의 위험을 방지함
- 하지만 분해에 따른 물리적 성능 하락을 고려해야 하므로, 논리 모델 단계에서는 정규화를 적극 수행한 후 물리 설계 단계에서 조인 깊이를 분석하여 선별적 반정규화나 캐싱 레이어를 적용하는 구조적 보완이 수반되어야 함

### 쉽게 이해하기 (학습용)
- 데이터의 정확성을 지켜주는 훌륭한 청소법이지만, 조인으로 인한 조회 속도 저하를 극복하기 위해 물리적 튜닝이나 조회용 테이블 합치기를 적절히 융합해야 함
