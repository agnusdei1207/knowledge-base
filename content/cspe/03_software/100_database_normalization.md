# 📖 【암기용】 개념 완전 이해

> 목적: 데이터베이스 정규화를 처음 보는 사람도 함수 종속, 1NF·2NF·3NF·BCNF, 반정규화의 관계를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 함수 종속을 기준으로 테이블을 분해해 중복과 갱신 이상을 줄이는 설계 기법
- **왜 필요한가**: 한 테이블에 고객·주문·상품 정보를 섞으면 삽입·수정·삭제 때 중복과 누락이 발생한다.
- **핵심 직관**: 한 사실은 한 곳에 저장하고, 필요한 때 키로 연결해 읽는 방식이다.

## 깊이 이해
- **배경·문제의식**: 중복 컬럼은 저장 공간보다 정합성 문제를 만든다. 고객 주소가 주문 행마다 반복되면 주소 변경 시 일부 행만 갱신되어 서로 다른 주소가 남을 수 있다.
- **작동 원리**: 함수 종속 `A -> B`는 A가 정해지면 B가 하나로 결정된다는 뜻이다. 1NF는 원자값, 2NF는 부분 종속 제거, 3NF는 이행 종속 제거, BCNF는 모든 결정자가 후보키가 되도록 분해한다.
- **비유**: 회사 인사카드에서 부서명은 부서번호 표에 한 번만 두고, 직원 표에는 부서번호만 적는 방식이다.
- **구체 예시**: `주문(주문ID, 고객ID, 고객명, 상품ID, 상품명)`은 고객명과 상품명이 반복된다. 고객·상품 테이블로 분리하면 고객명 변경 SQL 1회로 정합성을 유지한다.
- **흔한 오해·주의점**: 정규화는 무조건 높은 단계가 답이 아니다. 조회 p95 지연, Join 수, 변경 빈도에 따라 반정규화를 설계할 수 있다.

## 연결 개념
- 함수 종속 - 정규형 판단의 기준
- 관계형 데이터베이스 - 정규화가 적용되는 릴레이션 모델
- 반정규화 - 읽기 성능 요구에 따른 의도적 중복 설계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 정규형 단계, 함수 종속, 이상현상 제거, 반정규화 판단을 연결한다.
> 핵심: 정규화 답안은 1NF~BCNF 순서 암기가 아니라 중복 원인과 분해 기준을 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터베이스 정규화는 함수 종속을 분석해 릴레이션을 분해하고 삽입·수정·삭제 이상을 줄이는 설계 절차이다.
> 2. **가치**: 한 사실을 한 장소에 저장해 중복 갱신과 참조 불일치를 감소시키며, PK/FK 기반 무결성을 만든다.
> 3. **판단 포인트**: 정규형 단계, 무손실 분해, 종속성 보존, Join 비용, 반정규화 조건을 함께 판단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정규형 단계 이해 확인 | 1NF, 2NF, 3NF, BCNF | 단계명만 쓰고 함수 종속 기준 누락 |
| 이상현상 제거 원리 확인 | 삽입·수정·삭제 이상과 분해 | 중복 제거만 강조하고 무손실 분해 누락 |
| 실무 적용 판단 확인 | 정규화 vs 반정규화, Join 비용 | 높은 정규형을 항상 선택한다고 단정 |
> 요약: 정규화 문제는 함수 종속 기반 분해와 실무 반정규화 판단을 함께 요구한다.

## Ⅰ. 개요 및 필요성

정규화는 중복을 줄이는 릴레이션 설계 절차이다. 업무 사실이 여러 행에 반복되면 삽입·수정·삭제 이상이 발생한다. 함수 종속을 분석해 테이블을 분해하고 키 기반 참조로 연결하면 데이터 정합성을 DB 스키마에 반영할 수 있다.

---

## Ⅱ. 구조 및 구성요소

```text
업무 속성 수집 -> 함수 종속 분석
-> 1NF 원자값 -> 2NF 부분 종속 제거
-> 3NF 이행 종속 제거 -> BCNF 결정자 후보키화
-> PK/FK 연결 -> 무손실 분해 검증
```

| 구성요소 | 역할 | 판단 포인트 |
|:---|:---|:---|
| 함수 종속 | 속성 간 결정 관계 표현 | `X -> Y`, 후보키 도출 |
| 1NF | 반복 그룹 제거와 원자값 보장 | 다중값 컬럼 분리 |
| 2NF | 복합키 일부에만 종속된 속성 제거 | 부분 종속 제거 |
| 3NF | 비키 속성 간 이행 종속 제거 | `A -> B -> C` 분리 |
| BCNF | 모든 결정자를 후보키로 제한 | 3NF보다 엄격한 분해 |
> 요약: 정규화는 함수 종속을 기준으로 반복·부분·이행 종속을 차례로 제거하는 구조화 절차이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Relation R 분석 -> Candidate Key 식별
-> Functional Dependency 목록화
-> Normal Form 위반 탐지
-> Decompose Relation -> Lossless Join / Dependency Preservation 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 속성·후보키·기본키 식별 | 후보키 1개 이상 |
| 2 | 함수 종속과 다치 종속 분석 | FD 목록 완성 |
| 3 | 정규형 위반 판단 | 1NF~BCNF 조건 충족 여부 |
| 4 | 테이블 분해와 PK/FK 설계 | 무손실 조인 가능 |
| 5 | 성능 요구에 따라 반정규화 검토 | p95 지연, Join 수, 중복률 |
> 요약: 정규화는 키와 함수 종속을 먼저 찾고, 분해 후 무손실성과 종속성 보존을 검증한다.

## Ⅳ. 특징

| 구분 | 비정규 설계 | 정규화 설계 | 정량·판단 기준 |
|:---|:---|:---|:---|
| 중복 | 같은 사실 반복 저장 | 한 사실 한 위치 저장 | 중복 컬럼 수, 중복률 |
| 갱신 이상 | 일부 행만 변경 가능 | PK/FK로 변경 대상 명확 | 불일치 건수 0건 |
| 조회 비용 | 단일 테이블 조회 | Join 필요 | Join 수, p95 지연 |
| 변경 관리 | 컬럼 의미 혼재 | 엔티티별 스키마 분리 | DDL 영향 범위 |
> 요약: 정규화는 중복과 이상현상을 줄이지만 조회 Join 비용이 증가할 수 있어 성능 요구와 함께 판단한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 비정규 단일 테이블 | 3NF/BCNF 분해 | 갱신 빈도와 정합성 요구 |
| 비용/성능 | Join 감소, 중복 증가 | 중복 감소, Join 증가 | p95 200ms, 저장 중복률 10% 이하 |
| 운영/위험 | 갱신 이상 | 반정규화 관리 필요 | 정합성 오류 비용 vs 조회 비용 |
> 요약: 갱신 정합성이 우선이면 3NF 이상, 읽기 지연이 우선이면 통제된 반정규화를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과도한 Join | 세분화된 분해 | 조회 패턴 기반 반정규화 | p95 query latency |
| 종속성 손실 | 분해 후 FD 검증 부족 | Dependency Preservation 검사 | FD 위반 테스트 0건 |
| 중복 재발 | 반정규화 컬럼 관리 부재 | Trigger, Materialized View, CDC | 불일치 건수 |
> 요약: 정규화 리스크는 Join 비용, 종속성 손실, 반정규화 불일치이며 검증과 동기화 장치로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 정규형 | 주요 OLTP 테이블 3NF 이상 | 스키마 리뷰, FD 분석 |
| 무결성 | PK/FK 위반 0건 | 제약조건 검사 |
| 조회 성능 | 주요 SQL p95 200ms 이하 | EXPLAIN ANALYZE, APM |
> 요약: 정규화 성공 여부는 정규형 충족, 제약조건 위반, 주요 SQL 지연으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 설계 단계: ERD 작성 후 함수 종속 표를 만들고 주요 OLTP 테이블은 3NF 이상, 후보키·PK·FK를 DDL에 반영함
2. 검증 단계: 분해 테이블에 대해 무손실 조인과 종속성 보존을 확인하고 FK 위반 0건을 CI 데이터 테스트에 포함함
3. 반정규화 단계: p95 200ms 초과 Join 쿼리에 한해 Materialized View, 요약 테이블, 캐시를 적용하고 불일치 건수 0건을 모니터링함

**결론 (2줄):**
- 기술사 판단: 갱신 중심 OLTP는 3NF/BCNF를 기본으로 하고, 조회 병목은 통제된 반정규화로 해결함
- 향후 방향: 데이터 모델링은 정규화 원칙에 CDC·Materialized View·캐시 무효화를 결합해 정합성과 조회 성능을 함께 관리하는 방향임
