# 📖 【암기용】 개념 완전 이해

> 목적: AI 소프트웨어 감리를 일반 SW 감리와 다른 데이터·모델·윤리·운영 점검으로 이해하게 만든다.

## 한눈에
- **개요**: AI SW 감리는 데이터, 모델, 학습·평가, 편향, 설명가능성, 보안, 운영 모니터링을 점검하는 활동이다.
- **왜 필요한가**: AI 시스템은 코드가 같아도 데이터와 모델 버전에 따라 결과가 바뀐다. 정확도뿐 아니라 편향, 재현성, 개인정보, 모델 드리프트를 확인해야 한다.
- **핵심 직관**: 일반 SW가 레시피와 조리 과정을 감리한다면, AI SW는 재료(데이터), 조리법(학습), 맛 평가(성능), 알레르기 표시(위험 고지)까지 본다.

## 깊이 이해
- **배경·문제의식**: AI 서비스는 학습 데이터 품질, 모델 선택, 프롬프트, 파라미터, 운영 피드백에 따라 결과가 달라진다. 전통 감리의 요구사항-설계-구현 점검만으로는 재현성과 책임성을 확인하기 어렵다.
- **작동 원리**: 데이터 출처·라벨링·품질, 모델 학습·검증, 성능 지표, 편향·공정성, 설명가능성, 보안 공격, 운영 모니터링을 산출물과 로그로 확인한다.
- **비유**: 약품 심사에서 성분, 임상 데이터, 부작용, 제조 이력, 추적 관리까지 보는 것처럼 AI도 모델 산출물 전 과정을 본다.
- **구체 예시**: 이미지 분류 모델은 train/validation/test 분리, accuracy 95%, 재현율 90%, 성별·연령별 편차 5%p 이하, 모델 버전·데이터셋 해시 보관을 점검한다.
- **흔한 오해·주의점**: AI 감리는 정확도 점수만 보는 절차가 아니다. 데이터 권리, 재현성, 설명, 운영 드리프트, 보안 공격 대응까지 포함한다.

## 연결 개념
- MLOps - 모델 버전·배포·모니터링 관리
- AI TRiSM - 신뢰·위험·보안 관리
- ISO/IEC 42001 - AI 관리체계 참고 표준

# 📝 【답안용】 시험 답안 템플릿

> 목적: AI SW 감리 점검 항목을 데이터-모델-운영 생애주기 기준으로 전개한다.
> 핵심: AI 감리는 정확도보다 재현성, 편향, 설명가능성, 보안, 운영 드리프트 증적을 함께 본다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI SW 감리는 데이터·모델·학습·평가·운영 전 과정의 품질과 위험 통제를 확인하는 점검 활동이다.
> 2. **가치**: 모델 결과의 정확도, 재현성, 편향, 설명가능성, 개인정보, 모델 드리프트를 감리 증적으로 관리한다.
> 3. **판단 포인트**: 모델 성능 지표뿐 아니라 데이터셋 버전, 실험 로그, 승인 절차, 운영 모니터링을 함께 확인해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI와 일반 SW 감리 차이 확인 | 데이터·모델·학습·운영 점검 | 기능 테스트 중심 답안 |
| 신뢰성·책임성 판단 확인 | 편향, 설명가능성, 재현성, 개인정보 | accuracy만 제시 |
| 운영 리스크 점검 확인 | drift, retraining, model registry | 배포 후 모니터링 누락 |

> 요약: 이 문제는 AI 산출물의 생애주기와 위험 통제를 감리 항목으로 구조화하는지를 본다.

---

## Ⅰ. 개요 및 필요성

- 개요: 모델 기반 시스템의 품질·위험 점검
- 배경: AI 결과가 업무 의사결정에 영향을 주므로 일반 SW 감리 항목만으로 데이터와 모델 위험을 확인하기 어려움
- 필요성: 데이터, 학습, 평가, 배포, 운영 단계에서 정확도·편향·재현성·보안·드리프트 증적을 점검해야 함

---

## Ⅱ. 구조 및 구성요소

```text
데이터 -> 학습/검증 -> 모델 등록 -> 배포 -> 운영 모니터링
          / 편향 / 설명 / 보안 / 드리프트 / 재학습
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 점검 | 출처, 권리, 품질, 라벨 검증 | dataset hash, lineage |
| 모델 점검 | 알고리즘, 파라미터, 성능 확인 | model card, experiment log |
| 위험 점검 | 편향, 설명가능성, 보안 위협 확인 | fairness, XAI, adversarial test |
| 운영 점검 | drift, 재학습, 승인·롤백 관리 | model registry, monitoring |

> 요약: AI 감리는 데이터·모델·위험·운영을 분리해 증적과 지표로 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
감리 계획 -> 산출물 수집 -> 데이터/모델 검토 -> 운영 통제 확인 -> 개선 권고
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 영향도와 감리 범위 정의 | 업무 영향, 개인정보, 자동 판단 |
| 2 | 데이터셋·실험 로그·모델카드 수집 | 버전, 해시, 승인 이력 |
| 3 | 성능·편향·설명가능성 평가 | accuracy, recall, fairness gap |
| 4 | 보안·운영 통제 확인 | 접근권한, prompt injection, drift |
| 5 | 결함 등급과 조치 계획 제시 | 시정조치, 재점검 일정 |

> 요약: AI 감리는 산출물 수집 후 데이터·모델·운영 통제를 검토하고 시정조치로 연결한다.

---

## Ⅳ. 특징

| 구분 | 일반 SW 감리 | AI SW 감리 | 수치 컬럼 |
|:---|:---|:---|:---|
| 검토 대상 | 요구·설계·코드·테스트 | 데이터·모델·실험·운영 | dataset version 100% |
| 품질 지표 | 결함·테스트 통과율 | accuracy, recall, fairness gap | recall 90% 이상 |
| 운영 위험 | 장애·보안 | drift, hallucination, bias | drift PSI 0.2 초과 경보 |

> 요약: AI SW 감리는 코드 품질에 더해 데이터와 모델 결과의 재현성·편향·운영 변화를 점검한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | SDLC 감리 | AI 생애주기 감리 | 모델 자동 판단 여부 |
| 비용/성능 | 기능 테스트 중심 | 데이터·모델 평가 비용 포함 | 업무 영향도와 리스크 등급 |
| 운영/위험 | 배포 후 장애 대응 | drift·재학습·승인 관리 | 모델 변경 빈도 |

> 요약: 자동 판단 영향이 큰 AI 서비스일수록 감리 범위를 데이터와 운영 모니터링까지 확대한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 재현 불가 | 데이터·모델 버전 미보관 | registry, dataset hash | 재현 성공률 |
| 편향 결과 | 표본 불균형 | 계층별 성능 측정, 재샘플링 | fairness gap 5%p 이하 |
| 운영 품질 저하 | 데이터 분포 변화 | drift 모니터링, 재학습 승인 | PSI, error rate |

> 요약: AI 감리 리스크는 버전 관리, 계층별 성능, drift 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 | 출처·권리·라벨 품질 100% 확인 | lineage, sampling audit |
| 모델 | accuracy 95%, recall 90% 이상 | test set, confusion matrix |
| 운영 | drift PSI 0.2 초과 시 검토 | monitoring, model registry |

> 요약: AI 감리 성공은 데이터 적법성, 모델 성능, 운영 drift 통제가 증적으로 확인되는 경우다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 점검: 데이터 출처, 수집 근거, 라벨 품질, train/validation/test 분리, dataset hash를 감리 체크리스트에 포함
2. 모델 점검: model card, experiment log, hyperparameter, 성능 지표, 계층별 편향 분석 결과를 필수 산출물로 지정
3. 운영 점검: model registry, 승인 workflow, drift monitoring, rollback, prompt injection 테스트를 배포 통제에 반영

**결론 (2줄):**
- 기술사 판단: 추천·분류 보조 AI는 성능·drift 중심, 대출·채용·복지 자동 판단 AI는 편향·설명·권익 구제 증적을 우선한다
- 향후 방향: AI 감리는 ISO/IEC 42001, NIST AI RMF, MLOps와 결합해 AI 거버넌스 감리로 확장된다
