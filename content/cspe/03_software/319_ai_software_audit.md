# 📖 【암기용】 개념 완전 이해

> 목적: AI 소프트웨어 감리를 일반 SW 감리와 다른 데이터·모델·윤리·운영 점검으로 이해하게 만든다.

## 한눈에
- **개요**: AI SW 감리는 상위개념인 **정보시스템 감리**를 데이터·모델·학습·운영까지 확장한 것으로, 데이터, 모델, 성능지표, 편향, 설명가능성, 보안, 운영 드리프트를 점검하는 활동이다.
- **왜 필요한가**: 일반 SW는 같은 코드면 같은 결과가 나온다(결정론적). AI는 코드가 같아도 학습 데이터·모델 버전·파라미터가 바뀌면 결과가 달라진다(확률적·데이터 의존적). 그래서 코드 리뷰만으로는 "이 모델이 왜 이렇게 판단했는지, 계속 믿을 수 있는지"를 확인할 수 없다.
- **핵심 직관**: 일반 SW 감리가 레시피(코드)와 조리 과정(설계·구현)을 본다면, AI SW 감리는 재료(데이터 출처·품질), 조리법 재현성(학습 로그·버전), 맛 평가(성능지표), 알레르기 표시(편향·설명·위험 고지)까지 함께 본다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 정보시스템 감리 | 상위개념 — 요구·설계·구현·테스트 등 SDLC 산출물을 제3자가 점검하는 활동 | 공사 감리의 SW판 |
| AI 거버넌스 | 상위개념 — AI 위험을 조직 차원에서 관리하는 체계(정책·절차·통제) | AI판 내부통제 |
| 모델카드(Model Card) | 모델의 목적, 학습 데이터, 성능, 한계, 편향 정보를 기록한 표준 문서 | 의약품 첨부문서 |
| 데이터 계보(lineage) / 해시(hash) | 데이터가 어디서 와서 어떻게 가공됐는지 추적 기록 / 데이터 변조 여부를 확인하는 지문값 | 식품 이력추적제 |
| 혼동행렬(Confusion Matrix) | 예측과 실제를 TP·FP·FN·TN으로 나눠 정확도·재현율·정밀도를 계산하는 표 | 시험 채점표(맞음/틀림 교차분석) |
| 재현율(Recall) | 실제 양성 중 모델이 맞힌 비율 = TP/(TP+FN) | 실제 환자 중 못 찾은 사람이 얼마나 적은가 |
| 정밀도(Precision) | 양성 예측 중 실제로 맞은 비율 = TP/(TP+FP) | 양성 판정 중 오진이 얼마나 적은가 |
| 편향/공정성 격차(Fairness Gap) | 성별·연령 등 집단별 모델 성능(승인율 등) 차이 | 반 편성 시 특정 집단만 불리한 결과 |
| 설명가능성(XAI) | 모델이 왜 그 결과를 냈는지 사람이 이해할 수 있게 근거를 제시하는 능력 | 판사의 판결 이유서 |
| 모델 드리프트 / PSI | 운영 중 입력 데이터 분포가 학습 때와 달라져 성능이 저하되는 현상 / 그 변화를 수치화한 지표(Population Stability Index) | 옷이 몸에 맞았는데 체형이 변해 안 맞게 되는 것 |
| 적대적 공격 / 프롬프트 인젝션 | 입력을 조작해 모델을 오작동·정보유출시키는 공격 | AI판 SQL 인젝션 |
| 모델 레지스트리(Model Registry) | 모델 버전·승인 이력·롤백 대상을 관리하는 저장소 | 소스코드의 Git과 같은 모델판 버전관리 |

## 깊이 이해

### 왜 일반 SW 감리로는 부족한가 (배경)
- 일반 SW는 입력이 같으면 출력이 항상 같다(결정론적) — 그래서 요구사항-설계-코드-테스트 산출물만 점검하면 재현·검증이 가능하다.
- AI는 같은 코드라도 학습 데이터셋·하이퍼파라미터·랜덤시드가 바뀌면 다른 모델이 나온다(확률적). 코드 리뷰를 통과해도 "이 모델이 왜 이런 결정을 내렸는지", "6개월 뒤에도 똑같이 믿을 수 있는지"는 별도로 확인해야 한다. 이 간극을 메우는 것이 AI SW 감리다.

### 혼동행렬로 성능을 읽는 법 — 구체 수치 워크드 예제
- 대출심사 AI를 테스트셋 1,000건(실제 부도자 100건, 정상 900건)에 돌렸다고 하자.
- 결과: 부도자 100명 중 90명을 정확히 부도로 예측(TP=90), 10명을 정상으로 오판(FN=10, 실제 위험을 놓침). 정상 900명 중 45명을 부도로 오판(FP=45), 855명을 정확히 정상으로 예측(TN=855).
- 정확도(Accuracy) = (TP+TN)/전체 = (90+855)/1000 = 94.5% — 얼핏 높아 보인다.
- 재현율(Recall) = TP/(TP+FN) = 90/100 = 90% — 실제 부도자를 얼마나 놓치지 않았는가.
- 정밀도(Precision) = TP/(TP+FP) = 90/(90+45) ≈ 66.7% — 부도로 찍은 사람 중 진짜 부도는 3명 중 2명뿐, 나머지는 억울한 오탐.
- **왜 accuracy만 보면 안 되나**: 부도자가 원래 10%뿐인 불균형 데이터라, 모델이 전부 "정상"이라고만 찍어도 accuracy는 90%가 나온다. 그래서 감리는 accuracy 단독이 아니라 recall·precision을 함께 요구한다.

### 편향(fairness gap) 판별 — 구체 수치 워크드 예제
- 같은 대출심사 AI를 성별로 나눠 승인율을 비교한다. 남성 승인율 82%, 여성 승인율 75%라면 gap = 7%p.
- 업계 통상 기준으로 5%p를 넘는 격차는 "표본 불균형인지 실제 차별적 패턴을 학습했는지" 원인 분석이 필요한 경보 수준으로 본다. 감리는 이 임계치를 정하고, 초과 시 재학습·재샘플링·근거 문서화를 요구한다.

### 모델 드리프트와 PSI — 판별 원리와 구체 수치
- 드리프트는 "운영 중 실제 들어오는 데이터의 분포가 학습 때와 달라지는 것"이다. 예: 학습 당시 20대 고객이 40%였는데, 운영 1년 후 20대 비중이 15%로 줄고 50대가 늘었다면 모델이 학습 못 한 패턴을 마주하게 된다.
- PSI(Population Stability Index)는 이 변화를 구간별 분포 비율 차이(실제% - 기대%)에 로그비를 곱해 합산한 지표다. 업계 통상 판정 기준: PSI < 0.1은 안정, 0.1~0.25는 완만한 변화(모니터링 강화), 0.25 초과는 유의미한 변화(재학습·재검증 필요)로 본다.
- 감리는 이 PSI를 정기적으로 재는 모니터링 체계가 있는지, 임계치 초과 시 재학습·승인 절차가 정의돼 있는지를 점검한다.

### 설명가능성(XAI)이 필요한 이유
- 대출 거절, 채용 탈락처럼 개인에게 불이익을 주는 자동 판단은 "왜 그런 결과가 나왔는가"를 설명할 수 있어야 이의제기·권익구제가 가능하다.
- 감리는 SHAP·LIME 같은 설명 기법 적용 여부, 주요 판단 근거(feature importance)를 사용자에게 제시할 수 있는지를 확인한다. 설명 없이 "모델이 그렇게 판단했다"로 끝나면 책임 소재를 추적할 수 없다.

### 보안 관점 — 적대적 공격과 프롬프트 인젝션
- 이미지 분류 모델은 사람 눈에 안 보이는 미세한 노이즈를 넣어 오분류를 유도하는 적대적 공격(adversarial example)에 취약할 수 있다.
- 생성형 AI는 입력 프롬프트에 악성 지시를 숨겨 시스템 지침을 무력화하는 프롬프트 인젝션에 노출된다. 감리는 이런 공격 시나리오에 대한 테스트(레드팀 테스트)와 방어 체계 유무를 점검한다.

### 흔한 오해
- 오해 1: AI 감리는 accuracy 점수만 확인하면 끝이다 → 불균형 데이터에서는 accuracy가 착시를 준다(위 예제 참고). recall·precision·fairness·drift를 함께 봐야 한다.
- 오해 2: 배포 이후는 감리 대상이 아니다 → AI는 배포 후에도 데이터 분포가 변해 성능이 떨어질 수 있어(드리프트), 운영 모니터링이 감리의 핵심 영역이다.

## 연결 개념
- MLOps — 모델 버전·배포·모니터링을 자동화하는 운영 체계(모델 레지스트리·드리프트 감시와 직결)
- AI TRiSM — 신뢰·위험·보안 관리 프레임워크(편향·설명가능성·보안 점검을 포괄하는 상위 체계)
- ISO/IEC 42001 — AI 관리체계 국제표준(감리 점검항목의 참고 기준)

# 📝 【답안용】 시험 답안 템플릿

> 목적: AI SW 감리 점검 항목을 데이터-모델-운영 생애주기 기준으로 전개한다.
> 핵심: AI 감리는 정확도보다 재현성, 편향, 설명가능성, 보안, 운영 드리프트 증적을 함께 본다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI SW 감리는 데이터·모델·학습·평가·운영 전 과정의 품질과 위험 통제를 확인하는 점검 활동이다.
> 2. **가치**: 모델 결과의 정확도, 재현성, 편향, 설명가능성, 개인정보, 모델 드리프트를 감리 증적으로 관리한다.
> 3. **판단 포인트**: 모델 성능 지표뿐 아니라 데이터셋 버전, 실험 로그, 승인 절차, 운영 모니터링을 함께 확인해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI와 일반 SW 감리 차이 확인 | 데이터·모델·학습·운영 점검 | 기능 테스트 중심 답안 |
| 신뢰성·책임성 판단 확인 | 편향, 설명가능성, 재현성, 개인정보 | accuracy만 제시 |
| 운영 리스크 점검 확인 | drift, retraining, model registry | 배포 후 모니터링 누락 |

> 요약: 이 문제는 AI 산출물의 생애주기와 위험 통제를 감리 항목으로 구조화하는지를 본다.

## Ⅰ. 개요 및 필요성

- 개요: 모델 기반 시스템의 품질·위험 점검
- 배경: AI 결과가 업무 의사결정에 영향을 주므로 일반 SW 감리 항목만으로 데이터와 모델 위험을 확인하기 어려움
- 필요성: 데이터, 학습, 평가, 배포, 운영 단계에서 정확도·편향·재현성·보안·드리프트 증적을 점검해야 함

---

## Ⅱ. 구조 및 구성요소

```text
데이터 -> 학습/검증 -> 모델 등록 -> 배포 -> 운영 모니터링
          / 편향 / 설명 / 보안 / 드리프트 / 재학습
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 점검 | 출처, 권리, 품질, 라벨 검증 | dataset hash, lineage |
| 모델 점검 | 알고리즘, 파라미터, 성능 확인 | model card, experiment log |
| 위험 점검 | 편향, 설명가능성, 보안 위협 확인 | fairness, XAI, adversarial test |
| 운영 점검 | drift, 재학습, 승인·롤백 관리 | model registry, monitoring |

> 요약: AI 감리는 데이터·모델·위험·운영을 분리해 증적과 지표로 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
감리 계획 -> 산출물 수집 -> 데이터/모델 검토 -> 운영 통제 확인 -> 개선 권고
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 영향도와 감리 범위 정의 | 업무 영향, 개인정보, 자동 판단 |
| 2 | 데이터셋·실험 로그·모델카드 수집 | 버전, 해시, 승인 이력 |
| 3 | 성능·편향·설명가능성 평가 | accuracy, recall, fairness gap |
| 4 | 보안·운영 통제 확인 | 접근권한, prompt injection, drift |
| 5 | 결함 등급과 조치 계획 제시 | 시정조치, 재점검 일정 |

> 요약: AI 감리는 산출물 수집 후 데이터·모델·운영 통제를 검토하고 시정조치로 연결한다.

## Ⅳ. 특징

| 구분 | 일반 SW 감리 | AI SW 감리 | 수치 컬럼 |
|:---|:---|:---|:---|
| 검토 대상 | 요구·설계·코드·테스트 | 데이터·모델·실험·운영 | dataset version 100% |
| 품질 지표 | 결함·테스트 통과율 | accuracy, recall, fairness gap | recall 90% 이상 |
| 운영 위험 | 장애·보안 | drift, hallucination, bias | drift PSI 0.2 초과 경보 |

> 요약: AI SW 감리는 코드 품질에 더해 데이터와 모델 결과의 재현성·편향·운영 변화를 점검한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | SDLC 감리 | AI 생애주기 감리 | 모델 자동 판단 여부 |
| 비용/성능 | 기능 테스트 중심 | 데이터·모델 평가 비용 포함 | 업무 영향도와 리스크 등급 |
| 운영/위험 | 배포 후 장애 대응 | drift·재학습·승인 관리 | 모델 변경 빈도 |

> 요약: 자동 판단 영향이 큰 AI 서비스일수록 감리 범위를 데이터와 운영 모니터링까지 확대한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 재현 불가 | 데이터·모델 버전 미보관 | registry, dataset hash | 재현 성공률 |
| 편향 결과 | 표본 불균형 | 계층별 성능 측정, 재샘플링 | fairness gap 5%p 이하 |
| 운영 품질 저하 | 데이터 분포 변화 | drift 모니터링, 재학습 승인 | PSI, error rate |

> 요약: AI 감리 리스크는 버전 관리, 계층별 성능, drift 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 | 출처·권리·라벨 품질 100% 확인 | lineage, sampling audit |
| 모델 | accuracy 95%, recall 90% 이상 | test set, confusion matrix |
| 운영 | drift PSI 0.2 초과 시 검토 | monitoring, model registry |

> 요약: AI 감리 성공은 데이터 적법성, 모델 성능, 운영 drift 통제가 증적으로 확인되는 경우다.
