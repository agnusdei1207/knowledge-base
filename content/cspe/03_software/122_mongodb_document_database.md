## 미리 알고가기

- 도큐먼트 DB는 행 대신 JSON과 유사한 문서 단위로 데이터를 저장하는 NoSQL 계열임
- BSON은 MongoDB의 이진 문서 형식으로 중첩 객체·배열과 자료형 정보를 저장함
- 레플리카셋(Replica Set)은 주 복제본의 변경 로그를 보조 복제본에 전파해 장애 조치를 지원함
- 샤딩은 샤드 키로 데이터를 분할하고 여러 샤드에 분산 저장하는 방식임
- 쓰기 확인 수준(Write Concern)은 몇 개의 복제본이 기록을 확인해야 쓰기를 완료할지 정함

## 작성 근거(검토용)

- MongoDB는 문서 경계, 스키마 검증, 관계 처리, 트랜잭션 범위, 복제·샤딩을 핵심 판단축으로 설명함
- 비교표는 관계형 DB와 MongoDB의 저장·참조·확장 방식 차이가 선택 조건으로 이어지게 구성함
- 실무 사례는 상품 문서와 샤드 키 설계에서 조회 지연·문서 크기·부하 편차로 검증함

## Ⅰ. 개요

- **정의/개념**: MongoDB는 BSON 문서의 중첩 구조·가변 필드를 저장하고 복제·샤딩으로 분산 운영하는 도큐먼트 지향 NoSQL 데이터베이스임
- **배경/필요성**: 상품 속성·사용자 프로필처럼 구조 변화가 잦고 함께 조회하는 데이터가 중첩될 때 객체와 저장 단위의 차이를 줄이기 위해 문서 중심 데이터 모델이 필요함

## Ⅱ. 특징

- 한 문서에 중첩 객체·배열을 저장해 함께 읽고 갱신하는 데이터를 하나의 원자적 처리 단위로 구성함
- 필드 추가를 허용하면서 JSON 스키마 검증으로 문서별 필수 항목과 자료형을 제한함
- 보조 인덱스와 집계 파이프라인으로 문서 검색·변환·그룹 연산을 수행함
- 문서 내장으로 조인을 줄일 수 있지만 중복 데이터·문서 크기·다중 문서 갱신 비용을 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB | MongoDB |
|:---|:---|:---|
| 저장 단위 | 정형 행과 테이블 | BSON 문서와 컬렉션 |
| 스키마 통제 | 테이블 정의로 모든 행의 컬럼·자료형을 통제 | 문서별 필드를 허용하고 JSON 스키마로 선택 검증 |
| 관계 처리 | 외래키와 조인으로 정규화된 관계를 조회 | 문서 내장 또는 참조와 집계 조회로 관계를 처리 |
| 원자성 범위 | 테이블 간 다중 행 트랜잭션을 기본 사용 | 단일 문서 원자성이 기본이며 필요하면 다중 문서 트랜잭션 사용 |
| 수평 확장 | 복제·파티셔닝 구성을 별도 설계 | 샤드 키와 분산 라우터를 기본 확장 구조로 제공 |
| 적합 조건 | 관계·제약·다중 행 트랜잭션이 중심인 업무 | 함께 조회하는 중첩 데이터와 필드 변화가 많은 서비스 |

> 요약: 관계형 DB는 정형 스키마·조인·다중 행 트랜잭션에, MongoDB는 문서 경계·중첩 데이터·샤드 키 기반 확장에 초점을 둠.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터베이스·컬렉션 | 관련 BSON 문서를 논리 이름 공간과 문서 집합으로 묶음 |
| 문서 | 함께 읽고 갱신할 필드·중첩 객체·배열을 원자적 저장 단위로 구성함 |
| 인덱스 | 단일·복합·다중 키 필드의 검색과 정렬 경로를 제공함 |
| 레플리카셋 | 주 복제본의 변경 로그를 보조 복제본에 복제하고 장애 시 주 복제본을 선출함 |
| 샤딩 계층 | 분산 라우터·구성 서버·샤드가 샤드 키 범위와 요청 경로를 관리함 |

```text
애플리케이션 -> 분산 라우터 -> 샤드 -> 레플리카셋
                         |          |
                    구성 서버   문서·인덱스
```

> 요약: 분산 라우터가 구성 서버의 샤드 키 정보를 조회해 문서·인덱스를 보유한 레플리카셋으로 요청을 전달함.

## Ⅴ. 원리 및 절차 흐름도

```text
클라이언트 쓰기 -> 샤드 키 라우팅 -> 주 복제본 기록 -> 변경 로그 복제 -> 쓰기 확인
```

1. **쓰기 요청 수신**: 클라이언트가 문서와 쓰기 확인 수준을 분산 라우터에 전달함
2. **샤드 선택**: 분산 라우터가 샤드 키 범위를 조회해 대상 샤드를 결정함
3. **주 복제본 기록**: 대상 레플리카셋의 주 복제본이 문서와 변경 로그를 기록함
4. **변경 로그 복제**: 보조 복제본이 변경 로그를 가져와 같은 순서로 적용함
5. **쓰기 완료 응답**: 지정한 쓰기 확인 수준을 충족하면 클라이언트에 결과를 반환함

> 요약: 분산 라우터가 샤드를 선택하고 주 복제본의 변경 로그가 지정된 복제본 수에 반영되면 쓰기를 완료함.

## Ⅵ. 실무 사례

1. 상품 카탈로그는 함께 조회하는 속성을 문서에 내장하고 p95 조회 지연·평균 문서 크기를 확인함
2. 주문 이력 샤딩은 카디널리티가 높은 샤드 키를 적용하고 샤드별 데이터 편차·최대 요청 점유율을 확인함

## Ⅶ. 결론

- MongoDB는 문서 원자성 범위·관계 처리 방식·샤드 키 분포와 쓰기 확인 수준을 기준으로 적용해야 함
