## 미리 알고가기

- 지속적 배포는 검증을 통과한 변경을 사람 개입 없이 운영 반영하는 방식임
- 지속적 전달과 달리 마지막 운영 배포 승인도 자동화 대상임
- 강한 테스트와 관측과 롤백 체계가 전제되어야 함

## Ⅰ. 개요

- **정의/개념**: 지속적 배포는 코드 변경이 자동 검증과 품질 게이트를 통과하면 별도 수동 승인 없이 운영 환경까지 자동으로 배포되도록 하는 전달 방식임
- **배경/필요성**: 제품 개선 속도가 경쟁력인 서비스에서는 배포를 이벤트가 아니라 일상 흐름으로 만들어야 하므로, 운영 반영 자체를 자동화하는 전달 체계가 필요함

## Ⅱ. 특징

- 배포 리드타임을 크게 줄이고 작은 변경을 자주 운영에 반영함
- 배포 빈도가 높아질수록 변경 위험은 작아질 수 있음
- 검증 체계가 약하면 오류도 더 빠르게 운영에 퍼질 수 있음
- 자동 롤백과 피처 플래그와 관측 체계가 함께 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 지속적 전달 | 지속적 배포 |
|:---|:---|:---|
| 운영 반영 | 수동 승인 후 배포 | 자동 운영 배포 |
| 장점 | 통제와 자동화 균형 | 가장 빠른 전달 속도 |
| 한계 | 승인 대기 존재 | 강한 신뢰 체계 필수 |
| 적합 환경 | 규제/승인 필요 조직 | 고자동화 제품 조직 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Automated Test Suite | 운영 승인을 대체할 만큼 높은 신뢰도를 가진 자동 검증 장치임 |
| Release Policy | 어떤 변경이 자동 배포 가능한지 규정해 위험도를 통제함 |
| Progressive Rollout | 카나리나 블루-그린 같은 점진 배포로 오류 확산 범위를 줄임 |
| Fast Rollback Loop | 이상 징후 발생 시 즉시 되돌릴 수 있어 자동 배포 위험을 현실적으로 관리함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변경 병합      | --> | 자동 검증      | --> | 점진 배포      | --> | 관측/자동 롤백 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변경 병합**: main 변경이 배포 흐름을 시작함
2. **자동 검증**: 테스트와 보안과 품질 게이트를 통과함
3. **점진 배포**: 운영으로 자동 반영하되 점진적으로 트래픽을 확대함
4. **관측 및 자동 롤백**: 이상 징후가 보이면 즉시 복구함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 테스트 신뢰도가 낮으면 지속적 배포는 결함을 더 빠르게 운영으로 보내는 통로가 될 수 있음
   - 해결방안: 배포 게이트와 회귀 검증을 강화하고 change failure rate와 gate escape defect rate로 검증함
2. 문제: 운영 관측과 롤백 체계가 약하면 자동 배포 후 장애 탐지와 복구가 늦어질 수 있음
   - 해결방안: SLO 기반 자동 중단과 롤백을 적용하고 rollback time과 alert precision으로 검증함
3. 문제: 모든 변경을 동일하게 자동 배포하면 고위험 변경까지 과도하게 빠르게 노출될 수 있음
   - 해결방안: risk-based release policy를 운영하고 high-risk auto-release ratio와 incident severity distribution으로 검증함

## Ⅶ. 적용 사례

- SaaS 제품팀에서는 지속적 배포를 운영하고, deployment frequency와 rollback time로 결과를 확인함
- 고가용성 서비스에서는 점진 배포를 결합하고, alert precision과 change failure rate로 결과를 확인함
- 금융권 비핵심 채널 서비스에서는 위험 기반 정책을 적용하고, high-risk auto-release ratio와 incident severity distribution로 결과를 확인함

## Ⅷ. 결론

지속적 배포는 자동으로 자주 내보내는 기술이 아니라 자동 검증과 점진 배포와 빠른 복구가 한 세트로 작동할 때만 성립하는 운영 모델임.
