## 미리 알고가기

- 오프셋 페이지네이션은 `OFFSET n LIMIT m`으로 앞선 결과 수를 건너뛴 뒤 페이지를 읽는 방식임
- 키셋 페이지네이션은 직전 페이지의 마지막 정렬 키 이후 범위를 조건으로 조회하는 방식임
- 정렬 키는 시간·고유 ID 같은 복합 키로 중복 없는 전체 순서를 만듦
- 커서 토큰은 복합 정렬 키·방향·필터 정보를 클라이언트가 변경하지 못하도록 인코딩·서명한 값임
- 정렬 키 값이 갱신되거나 조회 조건이 바뀌면 키셋 방식에서도 중복·누락이 생길 수 있음

## 작성 근거(검토용)

- 비교표는 오프셋·키셋 페이지네이션의 인덱스 접근·데이터 변동·적합 조건을 대비함
- Ⅴ절은 커서 발급·검증과 복합 키 범위 조회라는 실제 요청 순서를 중심으로 구성함
- 실무 사례는 이벤트 피드와 관리자 화면에서 중복·누락·깊은 페이지 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 커서·키셋 페이지네이션은 직전 페이지의 마지막 복합 정렬 키를 커서로 전달하고 인덱스 범위 조건으로 다음 결과를 조회하는 목록 분할 기법임
- **배경/필요성**: 목록 깊이와 데이터 변경이 증가해도 앞선 행을 반복 건너뛰지 않고 일관된 전체 순서의 다음 구간을 조회하기 위해 키 기반 경계가 필요함

### 쉽게 이해하기 (학습용)
- 앞에서 몇 장을 건너뛰거나 마지막으로 본 항목 다음부터 이어 읽는 두 목록 탐색 방식임

## Ⅱ. 특징

- 마지막 복합 키 이후 조건과 같은 순서의 인덱스를 사용해 앞선 결과를 건너뛰는 비용을 줄임
- 고유한 전체 순서를 만들면 앞 구간의 삽입·삭제가 다음 페이지 경계를 이동시키는 문제를 줄임
- 불투명 커서에 정렬 키·방향·필터 버전을 넣어 서버가 다음 조회 조건을 복원함
- 페이지 번호를 직접 계산할 수 없어 임의 페이지 이동과 전체 페이지 수 표시에는 별도 질의가 필요함

### 쉽게 이해하기 (학습용)
- 키셋은 깊은 목록에 빠르고 안정적이지만 고유한 정렬 키와 임의 페이지 이동 제약이 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 오프셋 페이지네이션 | 커서·키셋 페이지네이션 |
|:---|:---|:---|
| 인덱스 접근 | 깊은 페이지에서 앞선 인덱스 항목을 건너뜀 | 커서 키에서 인덱스 범위 스캔 시작 |
| 데이터 변동 | 앞 구간 삽입·삭제가 이후 행의 위치를 이동시킴 | 정렬 키가 유지되면 앞 구간 변경에도 다음 경계 유지 |
| 적합 조건 | 전체 페이지·임의 이동이 필요한 관리 화면 | 연속 스크롤·이벤트 피드·대용량 API 목록 |

> 요약: 오프셋은 페이지 번호 이동에, 키셋은 복합 정렬 키 이후의 연속 범위 조회에 적합함.

### 쉽게 이해하기 (학습용)
- 오프셋은 책 쪽 번호, 키셋은 마지막 문장의 책갈피를 이용함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 복합 정렬 키 | 시간·고유 ID처럼 중복 없는 전체 순서와 페이지 경계를 만듦 |
| 커서 인코더·검증기 | 정렬 키·방향·필터 버전을 불투명 토큰으로 만들고 위변조를 검사함 |
| 범위 조건 생성기 | 정렬 방향에 맞춰 다음·이전 복합 키 비교 조건을 생성함 |
| 복합 인덱스 | 정렬 키와 범위 조건의 순서대로 결과를 읽음 |
| 응답 메타데이터 | 다음·이전 커서와 추가 결과 존재 여부를 반환함 |

```text
마지막 복합 키 -> 커서 토큰 -> 범위 조건 -> 복합 인덱스 -> 다음 페이지
```

> 요약: 마지막 복합 키를 검증 가능한 커서로 전달하고 같은 순서의 복합 인덱스에서 다음 범위를 조회함.

### 쉽게 이해하기 (학습용)
- 고유 정렬 키, 위변조 방지 책갈피, 범위 조건과 같은 순서의 색인으로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
커서 수신 -> 토큰 검증·복원 -> 범위 조건 조회 -> 추가 행 판정 -> 새 커서 발급
```

1. **커서 수신**: 첫 요청은 정렬·필터만, 다음 요청은 이전 커서를 함께 전달함
2. **토큰 검증·복원**: 서명·버전을 확인하고 복합 정렬 키·방향·필터를 복원함
3. **범위 조건 조회**: 복합 인덱스에서 커서 이후 결과를 페이지 크기보다 한 행 더 읽음
4. **추가 행 판정**: 초과 한 행으로 다음 페이지 존재 여부를 판단하고 응답에서는 제외함
5. **새 커서 발급**: 반환 페이지의 마지막 복합 키로 다음 커서를 생성함

> 요약: 커서를 검증해 복합 키 범위를 조회하고 한 행을 추가 확인해 다음 커서를 발급함.

### 쉽게 이해하기 (학습용)
- 책갈피를 풀어 마지막 키 다음 범위를 읽고 다음 책갈피를 발급함

## Ⅵ. 실무 사례

1. 이벤트 피드는 `(발생시각, 이벤트 ID)` 키셋을 적용하고 중복·누락 행 수와 p95 조회 지연을 확인함
2. 관리자 목록은 오프셋과 키셋을 화면별로 분리하고 최대 페이지 p95 지연·임의 페이지 이동 비율을 확인함

### 쉽게 이해하기 (학습용)
- 이벤트 피드는 키셋, 임의 페이지 이동이 필요한 관리 화면은 오프셋을 선택함

## Ⅶ. 결론

- 페이지네이션은 전체 순서·데이터 변동·임의 이동 요구와 복합 인덱스 범위를 기준으로 오프셋·키셋을 선택해야 함
- 커서에는 정렬·필터 버전과 서명을 포함하고 중복·누락·역방향 이동을 변경 데이터로 검증해야 함

### 쉽게 이해하기 (학습용)
- 책갈피에 정렬 규칙과 봉인을 넣고 책 내용이 바뀌어도 빠진 줄이 없는지 시험해야 함
