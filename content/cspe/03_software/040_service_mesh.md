## Ⅰ. 개요
- 정의: 서비스 간 통신(East-West)을 관리, 보호, 관찰하기 위한 인프라 계층의 전용 소프트웨어 계층.
- 출제 의도: MSA 환경의 통신 복잡성을 해결하기 위한 사이드카(Sidecar) 패턴 및 정책 제어 이해도 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  < Control Plane (Istiod) >
       | (Config / Policy)
  < Data Plane >
  [ App A ] <--- [ Proxy ] <--- Traffic ---> [ Proxy ] ---> [ App B ]
  (Sidecar)      (Envoy)                     (Envoy)      (Sidecar)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 데이터 플레인 | 서비스 옆에 붙어 모든 트래픽을 중계하는 사이드카 프록시 | 전담 비서 |
| 컨트롤 플레인 | 프록시들을 중앙에서 제어하고 정책을 하달하는 관리층 | 비서실장 |
| Envoy | 서비스 메쉬에서 표준으로 사용되는 고성능 L7 프록시 | 통역사/경호원 |
> 요약: 비즈니스 로직과 통신 로직을 분리하여 서비스 간 신뢰성을 확보함.

## Ⅲ. 절차
- ASCII 흐름도
  [사이드카 주입] -> [통신 가로채기] -> [정책 적용] -> [목적지 전달]
- 4단계 설명
1. Pod 생성 시 사이드카 프록시(Envoy)를 컨테이너 옆에 자동으로 배치함.
2. 애플리케이션의 모든 인/아웃바운드 트래픽을 프록시가 투명하게 수신함.
3. mTLS 암호화, 서킷 브레이커, 트래픽 쉐이핑 등 정의된 정책을 수행함.
4. 정책 검증이 완료된 요청만 최종 목적지 서비스로 전달함.
> 요약: 코드 수정 없이 네트워크 수준에서 지능적인 트래픽 관리를 수행함.

## Ⅳ. 문제점
- 오버헤드: 사이드카 프록시를 거치는 추가 네트워크 홉(Hop)으로 인해 지연 시간(Latency) 증가함.
- 복잡성 증대: 수많은 프록시 관리 및 컨트롤 플레인 운영 부하로 인프라 비용 상승함.

## Ⅴ. 개선방안
- Sidecarless (Ambient Mesh): 사이드카 없이 노드 단위 또는 eBPF 기반으로 통신 제어하여 성능 개선함.
- 최적화 설정: 불필요한 기능(로깅 등)을 끄고 필요한 통신 경로만 화이트리스트로 관리함.

## Ⅵ. 전망
- 보안 관점의 제로 트러스트(Zero Trust) 아키텍처 구현을 위한 필수 인프라로 정착될 것임.
- eBPF 기술 접목을 통해 커널 레벨에서 서비스 메쉬 기능을 수행하여 성능 한계 극복 시도 가속화됨.
- 멀티 클러스터 및 멀티 클라우드 환경을 연결하는 통합 통신 백본으로서의 역할 확대됨.
