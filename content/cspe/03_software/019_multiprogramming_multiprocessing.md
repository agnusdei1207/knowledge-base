## 미리 알고가기

- 다중프로그래밍은 하나의 CPU가 여러 작업을 번갈아 처리해 유휴 시간을 줄이는 방식임
- 다중처리는 여러 CPU나 코어가 실제로 동시에 작업을 수행하는 방식임
- 둘 다 처리량 증가를 목표로 하지만 자원 구조와 운영 방식이 다름
- 캐시 일관성: 여러 코어의 캐시에 저장된 동일 데이터 값을 동기화해 일치시키는 성질임

## 작성 근거(검토용)

- 두 방식은 단일 CPU 시간 분할과 다중 코어 동시 실행이라는 자원 구조로 구분함
- 실행 자원·주요 이슈·대표 적용 사례로 같은 수준에서 비교함
- 각 방식의 상태 전이를 Ⅴ절에 분리해 I/O 대기 시점과 동기화 시점의 차이를 검증함

## Ⅰ. 개요

- **정의/개념**: 다중프로그래밍은 한 CPU 환경에서 여러 프로그램을 교대로 실행해 자원 유휴를 줄이는 운영 방식이고, 다중처리는 둘 이상의 CPU 또는 코어가 동시에 작업을 수행하는 병렬 처리 구조임
- **배경/필요성**: 처리량 한계는 CPU 속도만으로 해결되지 않으므로, I/O 대기 시간 활용과 병렬 연산 자원 확장을 각각 담당하는 실행 모델이 필요함

## Ⅱ. 특징

- 다중프로그래밍은 한 작업의 I/O 대기 중 다른 작업에 CPU를 할당함
- 다중처리는 여러 코어에서 작업을 동시에 실행하며, 처리량과 응답시간 개선 폭은 병렬 구간과 동기화 비용에 따라 달라짐
- 다중프로그래밍은 스케줄링과 문맥 교환, 다중처리는 동기화와 캐시 일관성이 주요 판단 축임
- 작업의 I/O 대기 비율과 병렬 구간에 따라 두 방식을 함께 적용함

## Ⅲ. 종류 및 비교

| 판단 기준 | 다중프로그래밍 | 다중처리 |
|:---|:---|:---|
| 실행 자원 | 단일 CPU, 시간 분할에 의한 겉보기 동시성 | 다수 CPU·코어의 실제 동시 실행 |
| 주요 이슈 | 스케줄링·문맥 전환, 준비·I/O 대기 큐 관리 | 동기화·공유 자원 경쟁, 코어별 상태 관리 |
| 대표 적용 사례 | I/O 대기가 있는 배치·트랜잭션 | 병렬 계산·멀티스레드 서버 |

> 요약: 다중프로그래밍은 I/O 대기 중 다른 작업을 실행하고, 다중처리는 여러 코어에서 작업을 동시에 실행함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 준비 큐 | 다중프로그래밍의 실행 대기 작업을 관리함 |
| CPU 코어 집합 | 다중처리에서 동시에 실행할 작업 수를 결정함 |
| I/O 하위 시스템 | 한 작업의 I/O 대기 중 다른 작업의 CPU 실행을 지원함 |
| 동기화 기법 | 다중처리의 공유 데이터 접근 순서를 제어함 |

> 요약: 준비 큐와 I/O 상태는 교대 실행을, 코어 집합과 동기화 기법은 실제 병렬 실행을 지원함.

## Ⅴ. 원리 및 절차 흐름도

```text
[다중프로그래밍] 작업 A 실행 -> I/O 요청 발생 -> 문맥 전환 -> 작업 B 실행 -> I/O 완료 시 A 재개
[다중처리]       작업 분할 -> 코어별 동시 실행 -> 공유 자원 접근 시 동기화 -> 결과 병합
```

1. **다중프로그래밍**: 실행 중인 작업이 I/O를 요청하면 문맥을 전환해 다른 작업에 CPU를 배정함
2. **다중처리**: 여러 코어가 분할된 작업을 동시에 실행하고 공유 자원 접근 시 동기화로 순서를 제어함

> 요약: 다중프로그래밍은 I/O 대기 시점마다 문맥을 전환하고, 다중처리는 공유 자원 접근 시점마다 동기화함.

## Ⅵ. 실무 사례

1. 트랜잭션 서버는 동시 실행 작업 수를 조정하고 CPU 이용률과 초당 문맥 전환 수를 확인함
2. 멀티코어 계산 서버는 작업을 코어별로 분할하고 병렬 효율과 락 대기시간을 확인함

## Ⅶ. 결론

- I/O 대기 활용이 목적이면 다중프로그래밍, 실제 동시 실행이 필요하면 다중처리를 적용함
