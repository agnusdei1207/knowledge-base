## Ⅰ. 개요
- **정의**: 하나의 CPU에 여러 프로그램을 적재하여 I/O 대기 시간에 다른 프로그램을 실행하는 기법
- **배경/필요성**: CPU가 I/O 완료를 대기하는 유휴 시간을 줄여 자원 이용률을 높일 필요가 있음
- **비유**: 한 명의 요리사가 오븐 대기 시간에 다른 요리를 준비하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OS 발전 단계 이해 | 다중프로그래밍 vs 다중처리 vs 시분할 구분 | 다중프로그래밍은 병렬이 아닌 CPU 공유(비선점 가능)임을 명시 |

> 요약: CPU 유휴 시간을 최소화하기 위해 복수 프로그램을 메모리에 상주시키는 기법임

## Ⅱ. 구성요소
```text
Memory
+--------+--------+--------+--------+
| OS     | Prog A | Prog B | Prog C |
+--------+--------+--------+--------+
             |         |        |
             v         v        v
           CPU <-- Scheduler (I/O Wait --> Switch)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 작업 스케줄러 | 메모리에 적재할 작업을 선택하는 장기 스케줄러 | 대기실에서 진료실로 호출 |
| CPU 스케줄러 | 적재된 프로그램 중 실행 대상을 선택하는 단기 스케줄러 | 요리 순서 결정 |
| 메모리 파티션 | 프로그램별 독립 메모리 영역 할당 | 각 요리의 조리대 구역 |
| I/O 대기 큐 | I/O 요청 후 완료를 기다리는 프로세스 대기열 | 오븐 타이머 대기 목록 |

> 요약: 장기/단기 스케줄러와 메모리 파티션으로 복수 프로그램의 CPU 공유를 관리함

## Ⅲ. 절차
```text
작업 적재 --> CPU 할당 --> I/O 대기 발생 --> 문맥 교환
```
- 1단계: 장기 스케줄러가 디스크의 작업을 메모리 파티션에 적재
- 2단계: 단기 스케줄러가 Ready 상태 프로세스 중 하나를 CPU에 디스패치
- 3단계: 실행 중 I/O 요청 발생 시 해당 프로세스를 Blocked 상태로 전환
- 4단계: 문맥 교환으로 다른 Ready 프로세스에 CPU를 할당하여 유휴 시간 제거

> 요약: 적재-실행-I/O 대기-문맥 교환 순환으로 CPU 이용률을 높임

## Ⅳ. 문제점
- 메모리 단편화: 고정/가변 파티션 — 내부/외부 단편화로 적재 가능 프로그램 수 감소
- 보호 부재 위험: 프로세스 간 경계 침범 — 한 프로그램의 오류가 타 프로그램에 전파됨
- 응답 시간 미보장: 비선점 방식 가능 — I/O 집약 작업이 CPU를 장시간 점유 시 지연 발생

> 요약: 메모리 단편화·보호 부재·응답 지연이 다중프로그래밍의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 가상 메모리 도입으로 연속 할당 제약 제거 및 단편화 해소 (016 참조)
2. 중기: 베이스/리미트 레지스터 기반 메모리 보호로 프로세스 간 격리 강화
3. 장기: 선점형 시분할(Time-Sharing) 스케줄링으로 응답 시간 보장

> 요약: 가상 메모리, HW 보호, 시분할 스케줄링으로 다중프로그래밍 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 멀티코어·컨테이너 환경에서 다중프로그래밍 개념이 자원 격리 정책으로 계승됨
- 기술사적 판단: CPU 이용률 향상이라는 원칙은 클라우드 스케줄링에서도 핵심 설계 기준임
- 기술사 제언: 자원 공유 수준(CPU·메모리·I/O)별 격리 정책을 계층적으로 설계 필요
