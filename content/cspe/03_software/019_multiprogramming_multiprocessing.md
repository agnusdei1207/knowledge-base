# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **다중 프로그래밍(Multiprogramming)**은 "CPU가 놀지 못하게 프로그램 여러 개를 번갈아 가며 시키자(소프트웨어/OS 관점)"는 개념이고, **다중 처리(Multiprocessing)**는 "아예 CPU 코어 여러 개를 달아서 진짜로 동시에 일하자(하드웨어 관점)"는 개념이다.
- **왜 필요한가**: 초창기 컴퓨터는 한 번에 1개의 프로그램만 돌렸다. 디스크에서 데이터를 읽는 1초 동안 CPU는 아무것도 안 하고 팽팽 놀았다(CPU 유휴). 이 아까운 비싼 CPU를 100% 쥐어짜기 위해 다중 프로그래밍이 나왔고, 나중엔 CPU 자체의 물리적 한계(발열/클럭)를 극복하기 위해 코어를 여러 개 박는 다중 처리가 나왔다.
- **핵심 직관**: 
  - **다중 프로그래밍 (1 요리사, 여러 요리)**: 주방장(CPU)이 1명이다. 라면 물이 끓는 걸(I/O 대기) 기다리는 동안, 놀지 않고 옆 화구에서 계란말이(다른 프로세스)를 만든다. (가짜 동시성)
  - **다중 처리 (여러 요리사, 여러 요리)**: 주방장(코어)이 2명 이상이다. 한 명은 라면을 끓이고 한 명은 계란말이를 동시에 진짜로(Real) 만든다. (진짜 동시성)

## 깊이 이해
- **다중 프로그래밍 (Multiprogramming)**:
  - 목적: **CPU 활용률(Utilization) 극대화**.
  - 핵심 원리: A가 실행되다가 I/O(파일 읽기, 프린트 등)를 만나서 쉬어야 할 때(Blocked), OS가 즉시 A를 내쫓고 대기 중이던 B에게 CPU를 줘서 빈틈없이 굴린다.
  - 현대적 발전: 여기에 시계(타이머 인터럽트)를 달아서 0.01초마다 강제로 교대시키면, 사람이 볼 때 마치 100개 프로그램이 멈춤 없이 동시에 도는 것처럼 착각하게 되는데, 이를 **시분할(Time Sharing) 또는 멀티태스킹(Multitasking)**이라 부른다.
- **다중 처리 (Multiprocessing)**:
  - 목적: **전체 시스템의 절대적인 처리량(Throughput)과 속도 향상**.
  - 핵심 원리: 물리적인 프로세서(CPU 또는 코어) 2개 이상이 하나의 램(공유 메모리)을 쳐다보며 협동해서 일을 처리한다. (SMP 아키텍처)
  - 강력한 이점: 주방장 1명이 과로사(CPU 고장)해도 나머지 주방장이 일을 넘겨받아 식당이 굴러간다(결함 허용성, Fault Tolerance 보장).
- **비유**: 
  - 다중 프로그래밍: "체스 고수(CPU) 1명이 초보자 10명과 동시에 체스 두기". 1번 판에서 수를 두고, 1번 초보가 고민(I/O)하는 동안 2번 판으로 넘어가서 수를 둔다.
  - 다중 처리: "체스 고수 4명이 초보자 10명과 체스 두기". 진짜로 4판이 동시에 진행된다.
- **흔한 오해·주의점**: 다중 처리가 다중 프로그래밍을 대체한 것이 아니다! 현대 옥타(8) 코어 스마트폰은 코어 8개(다중 처리) 위에서 인스타, 카톡, 유튜브 등 100개의 앱을 쪼개서 번갈아 돌린다(다중 프로그래밍 결합). 두 개념은 완벽히 융합되어 돌아간다.

## 연결 개념
- **동시성(Concurrency) vs 병렬성(Parallelism)**: 
  - 동시성(다중 프로그래밍) = 1개의 CPU가 요리조리 번갈아 뛰며 동시에 도는 '환상'을 주는 논리적 개념.
  - 병렬성(다중 처리) = 진짜로 N개의 CPU가 물리적으로 동시에 연산하는 하드웨어적 개념.
- **컨텍스트 스위칭 (Context Switching)**: 다중 프로그래밍을 가능하게 하는 핵심 마술. 체스 판(레지스터) 상태를 1초에 수백 번 기억하고 덮어쓰는 과정.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 다중 프로그래밍은 단일 CPU의 I/O 유휴(Idle) 시간을 제거하기 위한 OS 수준의 논리적 동시성(Concurrency)이며, 다중 처리는 복수 CPU 코어 기반의 하드웨어적 병렬성(Parallelism)이다.
> 2. **가치**: 다중 프로그래밍은 CPU 활용률(Utilization)을 극대화하고 시분할 대화형 시스템을 완성했으며, 다중 처리는 물리적 처리량(Throughput) 한계 돌파와 결함 허용성(Fault Tolerance)을 보장한다.
> 3. **판단 포인트**: 문맥 교환(Context Switch) 기반의 소프트웨어적 접근(Multiprogramming)과 공유 메모리-멀티 프로세서(SMP) 구조의 하드웨어적 접근(Multiprocessing)을 맵핑 도식으로 명확히 대조해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 시스템 발전 역사에 따른 두 개념의 명확한 차이 | 논리적 동시성(시분할 쪼개기) vs 물리적 병렬성(동시 실행) | 두 용어를 단순히 "여러 개를 동시에 하는 것"으로 혼용하여 추상적으로 서술 |
| 아키텍처적 병목과 극복 메커니즘 | 다중프로그래밍(문맥 교환 오버헤드) / 다중처리(캐시 일관성, 버스 병목) | 다중 처리가 다중 프로그래밍의 대체재(과거 기술)라고 적는 논리적 오류 (상호 보완재임) |

> 요약: 다중 프로그래밍은 요리사 1명이 빈틈없이 일하게 만드는 스케줄링의 묘수이고, 다중 처리는 주방장 자체를 8명으로 늘려버린 물리적 물량 공세다. 현대 OS는 이 둘을 동시에 쓴다.

## Ⅰ. 개요 및 필요성

- 정의: 다중 프로그래밍은 2개 이상의 프로세스를 메모리에 올려 CPU 제어권을 교대로 넘겨주는 기법이며, 다중 처리는 2개 이상의 물리적 프로세서(CPU)가 단일 OS 통제하에 협력 연산하는 아키텍처
- 배경: 과거 일괄 처리(Batch) 시스템은 I/O 작업(디스크, 프린터) 대기 시간 동안 고가의 CPU가 유휴(Idle) 상태에 빠지는 막대한 자원 낭비 유발
- 필요성: CPU가 쉴 틈 없이 연산하게 만들어 활용률(Utilization)을 100%에 근접시키고(프로그래밍), 단일 코어의 물리적 클럭 주파수 상승 한계(발열)를 병렬 노드 추가로 돌파(처리)하기 위함

## Ⅱ. 다중 프로그래밍 vs 다중 처리 아키텍처 대조도

```text
[ 다중 프로그래밍 (Single Core + Time Slicing) ] -> 논리적 동시성
시간축 --->
CPU 0: [ Task A 10ms ] [ Task B 10ms ] [ Task C 10ms ] [ Task A ... ]
* 특징: 진짜 동시가 아님. I/O 블로킹 시 교대하거나 강제로 쪼개서(RR) 환상을 줌.

[ 다중 처리 (Multi Core + SMP) ] -> 물리적 병렬성
시간축 --->
CPU 0: [ Task A 실행 중 ==============================> ]
CPU 1: [ Task B 실행 중 ==============================> ]
* 특징: 진짜로 같은 시간에 2개의 명령어가 각각의 물리 코어에서 동시 폭발.
```

| 비교 축 | 다중 프로그래밍 (Multiprogramming) | 다중 처리 (Multiprocessing) |
|:---|:---|:---|
| **실행 주체** | 1개의 물리 프로세서 (단일 코어) | 2개 이상의 물리 프로세서 (멀티 코어) |
| **운영 철학** | 문맥 교환(Context Switch)을 통한 시분할 교대 | 독립된 ALU를 통한 명령어 동시 병렬 처리 |
| **목적과 가치** | CPU 활용도 극대화, 대화형 응답성(Response) | 절대 처리량(Throughput) 증가, 결함 허용(HA) |
| **시스템 오버헤드** | PCB/레지스터 상태 저장·복원 (문맥 교환 비용) | 코어 간 L1/L2 캐시 일관성(MESI 프로토콜) 유지 비용 |
| **극복해야 할 딜레마** | 스레싱 (메모리 꽉 참, 문맥 교환 폭주) | 버스(Bus) 경합 병목 및 락(Lock) 동기화 지연 |

> 요약: 다중 프로그래밍은 '시간'을 쪼개는 마법이고, 다중 처리는 '공간(하드웨어)'을 복사하는 물리 법칙이다.

## Ⅲ. 현대 SMP 아키텍처에서의 융합과 시너지

현대 서버나 스마트폰은 두 개념 중 하나를 택하지 않고 100% 융합(Symmetric Multiprocessing + Time Sharing)하여 구동한다.

| 아키텍처 동작 메커니즘 | 물리 계층 (다중 처리) | 소프트웨어 계층 (다중 프로그래밍) |
|:---|:---|:---|
| **로드 밸런싱 (부하 분산)** | 코어 1과 코어 2가 메인 램(RAM)을 공유(SMP) | 1번 코어 큐에 프로세스가 100개 몰리면(다중프로그래밍 부하), 커널이 2번 코어로 강제 이주(Migration) 시킴 |
| **인터럽트 분할 처리** | NIC(랜카드)가 패킷을 초당 10만 개 쏟아냄 | 0번 코어는 패킷 인터럽트만 처리하고, 남은 1~3번 코어는 다중프로그래밍 큐를 온전히 돌리며 부하 흡수 (RSS/RPS 튜닝) |
| **고가용성 (Fault Tolerance)** | 3번 코어가 물리적 열 손상으로 뻗음(Crash) | OS가 3번 코어를 격리(Off-line)하고 남은 3개 코어로 다중 프로그래밍 스케줄링을 이관하여 시스템 논스톱(Non-stop) 생존 |

> 요약: 다중 처리가 하드웨어 뼈대(인프라)를 여러 개 세워주면, 그 위에서 다중 프로그래밍(OS 스케줄러)이 수천 개의 프로세스를 미친 듯이 저글링하며 돌리는 완벽한 공생 관계다.

## Ⅳ. 극복해야 할 시스템적 한계 및 튜닝 방안

코어 수가 128개를 돌파하는 현대 데이터센터에서는 새로운 차원의 병목이 터진다.

| 리스크 요인 | 발생 시나리오 | 아키텍처 대응 방안 (실무 튜닝) |
|:---|:---|:---|
| 캐시 핑퐁 (Cache Bouncing) | A 프로세스가 1번 코어(다중처리)에서 쫓겨나고 2번 코어에서 재개(다중프로그래밍)될 때, 2번 코어의 L1 캐시가 콜드 미스(Cold Miss)를 내며 속도 반토막 | 스케줄러에 **CPU 선호도(Affinity/Pinning)**를 설정하여, 특정 프로세스는 무조건 1번 코어에서만 교대(다중프로그래밍)되도록 강제 고정 |
| NUMA 메모리 지연 | 다중 처리 노드가 거대해져 CPU 소켓 간 메모리 뱅크 거리가 멀어짐. 1번 소켓 CPU가 2번 소켓 메모리를 찌르느라 메모리 버스 지연(Latency) 폭발 | 메모리를 찌르는 스레드와 해당 데이터(RAM)가 물리적으로 같은 소켓 안에 위치하도록 **NUMA-Aware 스케줄링** 적용 (`numactl` 강제) |

> 요약: 주방장(코어)을 아무리 많이 뽑아놔도, 식재료 창고(메모리 버스)로 가는 복도가 하나뿐이면 거기서 다 막힌다. 현대 OS의 핵심은 캐시 오염을 막고 코어와 메모리의 물리적 거리를 계산하는 것이다.

## Ⅴ. 실무 적용 방안 및 결론

**적용 방안 3개:**
1. [Nginx 워커 스레드-코어 맵핑] 대용량 웹 서버 Nginx 운영 시 `worker_processes auto;` 설정으로 다중 처리(물리 코어 수)만큼 워커를 띄우고, `worker_cpu_affinity` 설정으로 워커와 CPU 코어를 1:1 바인딩시켜 문맥 교환 없는 논리/물리 융합 극상 성능 도출
2. [멀티 코어 DB 병렬 처리 (Parallel Query)] Oracle 등 RDBMS에서 인덱스 풀스캔 등 장기 실행(다중프로그래밍 점유) 쿼리를 날릴 때, 힌트(`/*+ PARALLEL(8) */`)를 주어 다중 처리(8개 코어) 유닛이 디스크 블록을 분할 스캔하도록 강제 지시하여 OLAP 분석 시간 압축
3. [안드로이드 big.LITTLE 전력 인지 제어] 모바일 디바이스에서 다중 프로그래밍 스케줄링 시, 백그라운드 다운로드(가벼움)는 저전력(LITTLE) 다중 처리 코어에 던지고 고사양 게임(무거움)은 고성능(big) 다중 처리 코어에 할당하는 EAS(Energy Aware Scheduling) 튜닝 적용

**결론:**
- 기술사 판단: 다중 프로그래밍은 "시간"을 잘게 썰어 속임수(가상화)를 부린 소프트웨어 혁명이고, 다중 처리는 "공간(트랜지스터)"을 복제해 속도의 물리적 한계를 깬 하드웨어 혁명이다. 두 기술의 트레이드오프(문맥 교환 오버헤드 vs 락 경합)를 완벽히 통제하는 것이 현대 커널 엔지니어링의 본질이다.
- 향후 방향: 무어의 법칙 한계로 CPU 클럭 상승이 멈춤에 따라 다중 처리는 메니코어(Many-core, 수백 개) 체제로 넘어가고 있으며, 다중 프로그래밍 스케줄러 역시 단순 시분할을 넘어 GPU 연산(CUDA) 파이프라인까지 포괄 통합하는 이기종(Heterogeneous) 스케줄링 아키텍처로 진화하고 있다.
