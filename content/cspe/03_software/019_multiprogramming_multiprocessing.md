## Ⅰ. 개요
- **정의**: 다중프로그래밍은 하나의 CPU에 여러 프로그램을 적재하여 교대 실행하는 기법이고, 다중처리는 복수 CPU로 동시 실행하는 기법임
- **배경/필요성**: CPU 유휴 시간을 줄이고 처리량을 극대화할 필요가 있음
- **비유**: 다중프로그래밍은 요리사 한 명이 여러 요리를 번갈아 하는 것, 다중처리는 요리사 여러 명이 동시에 요리하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병행·병렬 처리 구분 | 논리적 동시성 vs 물리적 동시성 | 다중프로그래밍과 시분할(Time-sharing) 혼동 금지 |

> 요약: CPU 활용률 극대화를 위한 논리적(다중프로그래밍)·물리적(다중처리) 동시 실행 기법임

## Ⅱ. 구성요소
```text
Multiprogramming          Multiprocessing
+--------+               +--------+--------+
| CPU    |               | CPU-0  | CPU-1  |
|  P1    |               |  P1    |  P2    |
|  P2(w) |               |  P3    |  P4    |
|  P3(w) |               +--------+--------+
+--------+                   | shared memory |
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 작업 스케줄러 | 메모리에 적재할 작업 집합을 선택함 | 대기실에서 진료 순서 결정 |
| CPU 스케줄러 | Ready 상태 프로세스 중 실행 대상을 선택함 | 요리사가 다음 요리 선택 |
| 문맥 교환 | CPU 상태를 저장·복원하여 프로세스를 전환함 | 요리 도구를 교체하며 작업 전환 |
| 프로세서 간 통신 | 다중처리 시 CPU 간 데이터를 공유·동기화함 | 요리사들 간 재료 전달 |

> 요약: 스케줄러·문맥 교환·프로세서 간 통신이 다중 실행을 지원함

## Ⅲ. 절차
```text
작업 적재 --> CPU 스케줄링 --> 실행/대기 전환 --> 완료/재스케줄링
```
- 1단계: 장기 스케줄러가 디스크의 작업을 메모리에 적재함
- 2단계: 단기 스케줄러가 Ready 큐에서 실행할 프로세스를 선택함
- 3단계: I/O 대기 등 발생 시 문맥 교환으로 다른 프로세스에 CPU를 할당함
- 4단계: 프로세스 완료 또는 시간 할당 만료 시 재스케줄링을 수행함

> 요약: 적재 → 스케줄링 → 문맥 교환 → 재스케줄링 순서로 동작함

## Ⅳ. 문제점
- 문맥 교환 비용: 잦은 전환 시 레지스터 저장·복원 오버헤드가 누적됨
- 메모리 경합: 다수 프로세스 동시 적재 시 물리 메모리 부족으로 스래싱 발생 가능함(016 참조)
- 캐시 간섭: 다중처리 시 프로세서 간 캐시 일관성 유지 비용이 증가함

> 요약: 문맥 교환 비용, 메모리 경합, 캐시 간섭이 주요 병목임

## Ⅴ. 개선방안
1. 단기: 경량 스레드(lightweight thread) 활용으로 문맥 교환 비용을 절감함
2. 중기: 워킹셋 기반 적재 제어(018 참조)로 메모리 경합과 스래싱을 억제함
3. 장기: NUMA 인지 스케줄링으로 프로세서-메모리 친화성을 확보하여 캐시 간섭을 최소화함

> 요약: 경량 스레드 → 워킹셋 제어 → NUMA 인지 스케줄링 순으로 개선함

## Ⅵ. 전망
- 발전 방향: 이기종 멀티코어(big.LITTLE)에서 에너지 효율 고려 스케줄링이 확산됨
- 기술사적 판단: OS 자원 관리의 근본 원리로 클라우드·컨테이너 환경에서도 유효함
- 기술사 제언: 워크로드 특성별 스케줄링 정책 선택 기준을 수립할 필요가 있음
