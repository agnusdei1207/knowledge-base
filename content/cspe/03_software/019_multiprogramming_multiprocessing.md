# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 다중프로그래밍(Multiprogramming)은 단일 CPU에서 여러 프로세스를 번갈아 실행하는 **동시성(Concurrency)** 기법이고, 다중처리(Multiprocessing)는 복수 CPU/코어로 프로세스를 물리적으로 동시에 실행하는 **병렬성(Parallelism)** 기법임.
- **왜 필요한가**: 프로세스가 디스크 I/O를 기다리는 동안 CPU가 유휴 상태에 빠지는 낭비를 없애고(다중프로그래밍), 단일 코어의 클럭 속도 한계를 코어 수 확장으로 돌파하기 위함(다중처리).
- **핵심 직관**: 요리사 1명이 국이 끓는 동안 채소를 써는 것이 다중프로그래밍(번갈아 처리), 요리사 3명이 각자 다른 요리를 동시에 만드는 것이 다중처리(병렬 처리)임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 동시성 (Concurrency, 상위 키워드) | 논리적으로 동시에 진행되는 것처럼 보이도록 빠르게 교대 | 1인이 여러 요리를 왔다 갔다 |
| 병렬성 (Parallelism, 상위 키워드) | 물리적으로 동일 시각에 여러 연산을 실행 | 여러 명이 각자 요리 |
| 다중프로그래밍 | 메모리에 복수 프로세스 적재 후 I/O 대기 시 CPU를 다른 프로세스에 양보 | 대기 시간에 딴 일 |
| 시분할 (Time Sharing) | 다중프로그래밍을 짧은 타임 슬라이스(10~100ms)로 분할해 대화형 응답성 확보 | 0.01초 단위 교대 |
| SMP (Symmetric Multiprocessing) | 모든 코어가 동등한 권한으로 공유 메모리에 접근하는 대칭형 구조 | 평등한 요리사들 |
| ASMP (Asymmetric Multiprocessing) | 마스터 코어가 스케줄링을 전담하고 나머지가 실행만 담당 | 주방장 + 보조 |
| 캐시 일관성 (Cache Coherence) | 여러 코어의 캐시가 동일 메모리에 대해 같은 값을 유지하도록 보장 | 모두 같은 레시피를 보는 것 |

## 깊이 이해
- **배경·문제의식**: 초기 컴퓨터는 한 프로그램이 끝나야 다음을 실행했으나, I/O 시간이 CPU 연산의 수백~수천 배 느려 CPU 이용률이 10~20%에 머물렀음. 이를 해결하기 위해 메모리에 여러 프로세스를 올리고 I/O 대기 시 즉시 전환하는 다중프로그래밍이 등장함. 이후 무어의 법칙이 클럭 주파수가 아닌 코어 수 방향으로 전환(2005년, 인텔 Pentium D)되면서 다중처리가 주류 아키텍처가 됨.
- **작동 원리**:
  - 다중프로그래밍: 프로세스 A가 디스크 I/O를 요청하면 Block 상태로 전환하고, Ready 큐의 프로세스 B에 CPU를 할당(Context Switch). A의 I/O 완료 인터럽트 도착 시 A를 Ready로 복귀시킴.
  - 다중처리(SMP): 코어1은 프로세스 A를, 코어2는 프로세스 B를 물리적으로 동시 실행. 공유 메모리 접근 시 MESI 프로토콜이 캐시 라인의 Modified/Exclusive/Shared/Invalid 상태를 관리해 일관성을 보장함.
- **비유**: 은행 창구 1개에서 손님이 서류 작성(I/O)하는 동안 다른 손님을 불러 업무 처리(다중프로그래밍) vs 창구 4개에서 4명을 동시에 처리(다중처리).
- **구체 예시**: 싱글 코어 시절 Windows XP에서 음악 재생과 워드 편집이 동시에 되는 것은 시분할(다중프로그래밍). 현재 8코어 CPU에서 영상 인코딩(코어 1~4) + 게임 렌더링(코어 5~8)을 병렬로 수행하는 것은 다중처리.
- **흔한 오해·주의점**: (1) 두 용어를 혼용하면 안 됨 — 다중프로그래밍은 S/W 스케줄링(동시성), 다중처리는 H/W 코어 복수 탑재(병렬성). (2) 현대 OS는 다중처리 하드웨어 위에서 다중프로그래밍(시분할)을 결합해 동작하므로, 두 개념은 대립이 아닌 보완 관계임. (3) 코어를 늘려도 직렬화 구간(Amdahl's Law)이 있으면 성능이 비례하지 않음.

## 연결 개념
- (004 프로세스 스케줄링) 다중프로그래밍의 핵심 메커니즘인 CPU 스케줄링 알고리즘
- (012 세마포어·뮤텍스·모니터) 다중처리 환경의 공유 메모리 동기화 기법
- (031 NUMA 인지 스케줄링) SMP의 버스 병목을 해소하는 비균일 메모리 아키텍처

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 다중프로그래밍은 I/O 대기 시간을 활용해 CPU 이용률을 높이는 동시성 기법이고, 다중처리는 복수 코어로 물리적 병렬 연산을 수행하는 아키텍처임.
> 2. **가치**: 전자는 시분할과 결합해 사용자 응답성을 확보하고, 후자는 클럭 한계를 넘어 처리량(Throughput)을 코어 수에 비례해 확장함.
> 3. **판단 포인트**: 코어 수 확장 시 캐시 일관성(MESI), 버스 경합, 암달의 법칙에 의한 직렬화 병목을 아키텍처 레벨에서 통제해야 실효적 성능 향상이 가능함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 운영체제 발전과 자원 활용 메커니즘 차이 이해 | 동시성(Concurrency) vs 병렬성(Parallelism)의 구조적 차이 | 두 개념 혼용, 차이 모호 서술 |
| 멀티코어 환경의 과제와 해결 방안 도출 | SMP 캐시 일관성(MESI), 거짓 공유, 암달의 법칙 | 개념 나열에 그치고 런타임 리스크 누락 |

> 요약: 다중프로그래밍은 S/W 스케줄링 최적화, 다중처리는 H/W 아키텍처 확장으로 접근해 각각의 목적·기술적 허들을 대비시켜야 함.

## Ⅰ. 개요 및 필요성

- 개요: 복수 프로세스의 CPU 이용률과 처리량을 극대화하기 위한 운영체제 자원 관리 기법임
- 배경: 프로세스 I/O 대기 시 CPU 유휴(이용률 10~20%), 단일 코어 클럭 한계(발열·전력)로 성능 증가 정체
- 필요성: 단위 시간당 처리량 극대화, 대화형 응답 시간 단축, 연산 워크로드의 스케일업을 위해 두 기법의 통합 운용이 필수임

---

## Ⅱ. 구조 및 구성요소

```text
[다중프로그래밍 — 단일 코어]
Ready Queue -> CPU 스케줄러 -> 프로세스 A 실행 -> I/O 발생 -> Context Switch -> 프로세스 B 실행

[다중처리 — SMP]
Ready Queue -> 로드 밸런서
  -> 코어 1: 프로세스 A 실행 \
                               +-> 시스템 버스 -> 공유 메모리 (MESI 캐시 일관성)
  -> 코어 2: 프로세스 B 실행 /
```

| 구성요소 | 역할 | 비고 |
|:---|:---|:---|
| CPU 스케줄러 | Ready 큐에서 다음 프로세스를 선택해 CPU 할당 | FCFS, RR, CFS 등 알고리즘 적용 |
| 문맥 교환기 (Context Switcher) | 현재 프로세스의 레지스터·PCB를 저장하고 다음 프로세스를 복원 | 교환 비용 수 μs |
| 로드 밸런서 | 다중처리 시 코어 간 프로세스를 균등 분배 | Push/Pull Migration |
| 시스템 버스·캐시 일관성 프로토콜 | 코어 간 공유 메모리 접근 시 데이터 정합성 유지 | MESI, MOESI 등 |

> 요약: 다중프로그래밍은 스케줄러·문맥 교환으로 시간을 분할하고, 다중처리는 로드 밸런서·캐시 일관성으로 공간(코어)을 분할함.

---

## Ⅲ. 동작원리 및 흐름도

```text
프로세스 생성 -> Ready Queue 등록
  -> 로드 밸런서: 코어별 부하 확인 후 코어 할당 (다중처리)
    -> 코어 내: 타임 슬라이스 소진 또는 I/O 발생 시 Context Switch (다중프로그래밍)
      -> 캐시 일관성: 공유 데이터 접근 시 MESI Snooping으로 정합성 검증
        -> 결과: CPU 이용률 향상 + 처리량 선형 근접 확장
```

1. 작업 배분: 큐의 프로세스를 여러 코어에 균형 분산(로드 밸런싱, 다중처리)
2. 논리적 교환: 개별 코어 내에서 I/O 요청 시 Block 처리 후 다른 Ready 프로세스 투입(다중프로그래밍)
3. 공유 자원 통제: 복수 코어가 동일 메모리 주소 참조·수정 시 캐시 스누핑으로 정합성 유지
4. 확장 실행: 두 기법 융합으로 전체 처리량이 코어 수에 비례에 근접하여 향상됨

> 요약: 다중처리가 물리적 실행 공간(코어)을 제공하고, 각 코어 내에서 다중프로그래밍이 시간을 분할해 종합 효율을 달성함.

## Ⅳ. 특징

- 동시성 vs 병렬성: 다중프로그래밍은 빠른 교대로 동시 실행 효과를 내고, 다중처리는 물리적 완전 동시 실행이므로 동시성 성격이 근본적으로 다름
- 병목 지점 차이: 다중프로그래밍은 Context Switch 오버헤드(수 μs/회)가, 다중처리는 메모리 버스 경합·Lock 경합이 각각의 병목임
- 암달의 법칙 적용: 코어 N개 투입 시 속도 향상은 1/(S + (1-S)/N)이며, 직렬 구간 비율 S가 10%면 코어 무한 투입해도 최대 10배까지만 향상됨
- 현대 통합: 현재 OS는 다중처리 H/W 위에 다중프로그래밍(시분할)을 결합해 동시성과 병렬성을 모두 활용함

> 요약: 다중프로그래밍 병목은 Context Switch 비용, 다중처리 병목은 암달의 법칙에 따른 직렬화 구간과 메모리 경합임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 다중프로그래밍 | 다중처리(SMP) | 선택 기준 |
|:---|:---|:---|:---|
| 목표 | CPU 이용률 극대화 | 절대 처리량(Throughput) 증가 | 자원 효율 vs 연산량 확장 |
| 확장 방식 | 프로세스 수 증가(MPL 조정) | 코어 수 증가(Scale-up) | I/O 바운드면 전자, CPU 바운드면 후자 |
| 주요 비용 | Context Switch 오버헤드 | 캐시 일관성·버스 대역폭 | 교환 빈도 vs 공유 데이터량 |
| 한계 | 코어 1개의 연산력 상한 | 암달의 법칙, 코어 16+ 시 SMP 버스 포화 | NUMA 전환 판단 필요 |

> 요약: I/O 바운드 워크로드는 다중프로그래밍으로 CPU 유휴를 제거하고, CPU 바운드 워크로드는 다중처리로 코어를 확장하되 직렬화 구간 최소화가 핵심임.

**리스크·대응:**
- 거짓 공유(False Sharing): 인접 변수가 같은 캐시 라인에 위치해 코어 간 무효화 반복 -> 구조체 패딩으로 캐시 라인(64B) 분리 (지표: L2 Cache Miss Rate)
- SMP 버스 포화: 코어 16+ 환경에서 공유 버스 병목으로 코어 추가 효과 정체 -> NUMA 아키텍처 전환, 로컬 메모리 우선 할당 (지표: 원격 메모리 접근 비율)

**도입 후 점검 지표:**
- 성능: 코어 수 대비 처리량 확장 선형성(Scalability Factor) — 암달의 법칙 이론치 대비 실측 비교
- 운영: Lock Contention 시간(perf lock 통계), Context Switch 횟수(vmstat cs/s) 안정 유지 여부

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU 친화도(Affinity) 설정: 잦은 코어 이동으로 L1/L2 캐시 손실이 발생하는 프로세스를 `taskset`으로 특정 코어에 고정(Pinning)해 캐시 히트율을 확보함
2. NUMA-Aware 메모리 할당: Oracle·PostgreSQL 등 RDBMS에서 `numactl --localalloc`로 로컬 노드 메모리 우선 사용을 강제해 원격 메모리 접근 지연을 차단함
3. Lock-Free 자료구조 도입: 스핀락 직렬화가 병목인 구간을 CAS(Compare-And-Swap) 기반 무잠금 큐·스택으로 대체해 다중처리 환경의 병렬성을 극대화함

**결론:**
- 기술사 판단: 코어 증설만으로는 암달의 법칙에 의해 성능이 포화하므로, S/W 직렬화 구간(Lock) 제거와 H/W 메모리 지역성(Affinity·NUMA) 보장을 동시에 튜닝해야 함
- 향후 방향: CPU 동종 다중처리를 넘어 GPU·NPU·DPU를 결합한 이기종(Heterogeneous) 다중처리 패러다임으로 워크로드별 최적 코어에 분배하는 방향으로 진화 중임
