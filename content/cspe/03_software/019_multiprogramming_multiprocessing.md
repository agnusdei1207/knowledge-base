## 미리 알고가기

- 다중프로그래밍은 하나의 CPU가 여러 작업을 번갈아 처리해 유휴 시간을 줄이는 방식임
- 다중처리는 여러 CPU나 코어가 실제로 동시에 작업을 수행하는 방식임
- 둘 다 처리량 증가를 목표로 하지만 자원 구조와 운영 방식이 다름

## Ⅰ. 개요

- **정의/개념**: 다중프로그래밍은 한 CPU 환경에서 여러 프로그램을 교대로 실행해 자원 유휴를 줄이는 운영 방식이고, 다중처리는 둘 이상의 CPU 또는 코어가 동시에 작업을 수행하는 병렬 처리 구조임
- **배경/필요성**: 처리량 한계는 CPU 속도만으로 해결되지 않으므로, I/O 대기 시간 활용과 병렬 연산 자원 확장을 각각 담당하는 실행 모델이 필요함

## Ⅱ. 특징

- 다중프로그래밍은 CPU와 I/O 자원의 겹침으로 처리량을 높임
- 다중처리는 실제 병렬 실행으로 응답 지연과 총 처리량을 함께 개선함
- 다중프로그래밍은 스케줄링과 문맥 교환, 다중처리는 동기화와 캐시 일관성이 주요 판단 축임
- workload 특성에 따라 두 방식을 함께 사용할 수도 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 다중프로그래밍 | 다중처리 |
|:---|:---|:---|
| 실행 자원 | 보통 단일 CPU 중심 | 다수 CPU 또는 코어 |
| 병렬성 형태 | 시간 분할에 의한 겉보기 동시성 | 실제 동시 실행 |
| 주요 목표 | CPU 유휴 시간 감소 | 계산 성능과 처리량 확대 |
| 주요 이슈 | 스케줄링과 context switch | 동기화와 공유 자원 경쟁 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Ready Queue | 다중프로그래밍에서 실행 대기 작업을 관리해 CPU 유휴 시간을 줄임 |
| CPU Core Set | 다중처리에서 병렬 실행 가능한 실제 자원으로 스케줄링 폭을 결정함 |
| I/O Subsystem | CPU 실행과 I/O 대기를 겹치게 해 유휴 시간을 줄이는 자원임 |
| Synchronization Mechanism | 다중처리에서 공유 데이터 무결성과 병렬 실행 비용을 좌우함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 등록      | --> | 자원 배치      | --> | 교대 또는 병렬 실행 | --> | 동기화/완료   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 등록**: 여러 작업이 ready 상태나 대기 상태로 시스템에 들어옴
2. **자원 배치**: 스케줄러가 CPU와 I/O와 코어에 작업을 배정함
3. **교대 또는 병렬 실행**: 단일 CPU는 교대로 실행하고 다중처리는 여러 코어에서 동시에 실행함
4. **동기화 및 완료**: 공유 자원 보호와 결과 회수를 수행함

## Ⅵ. 실무 적용 및 유의점

1. I/O 대기가 많은 배치나 트랜잭션 시스템에서는 다중프로그래밍으로 CPU 유휴를 줄이되 작업 수를 과도하게 늘리면 문맥 교환과 메모리 압박이 커지므로 degree of multiprogramming을 조정하고 CPU utilization과 context switch rate와 swap I/O rate로 확인함
2. 멀티코어 계산 서버에서는 다중처리를 쓰되 lock 경쟁과 캐시 일관성 비용이 병목이 되지 않게 데이터 지역성과 lock 분할을 설계하고 parallel efficiency와 lock wait time으로 확인함

## Ⅶ. 결론

다중프로그래밍과 다중처리는 모두 처리량 증가를 노리지만 전자는 유휴 시간 활용에, 후자는 실제 병렬 실행에 초점이 있으므로 병목 원인에 맞춰 구분해 써야 함.

## 작성 근거(검토용)

- 두 방식의 차이는 속도보다 단일 CPU 시간 분할과 다중 코어 실제 병렬 실행이라는 실행 구조로 구분해야 함
- 추상 성능어를 줄이고 ready queue, I/O 겹침, 동기화, 캐시 일관성 같은 설계 판단 축으로 바꿈
