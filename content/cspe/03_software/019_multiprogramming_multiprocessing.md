## Ⅰ. 개요
- **정의**: 하나의 CPU에서 여러 프로그램을 메모리에 적재하고 I/O 대기 시 다른 프로그램을 실행하는 기법
- **배경/필요성**: 단일 프로그램 실행 시 I/O 대기 동안 CPU가 유휴 상태가 되어 활용률이 낮아짐
- **비유**: 세탁기가 돌아가는 동안 설거지를 하여 전체 가사 시간을 줄이는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 다중프로그래밍·다중처리·다중태스킹 구분 | CPU 수 vs 동시 적재 프로그램 수 기준 차이 | 다중프로그래밍은 단일 CPU 기법임을 명확히 할 것 |

> 요약: I/O 유휴 시간에 다른 프로그램을 실행하여 CPU 이용률을 높이는 기법임

## Ⅱ. 구성요소
```text
Memory
+--------+--------+--------+--------+
| OS     | Prog A | Prog B | Prog C |
+--------+--------+--------+--------+
             |        |        |
             v        v        v
          CPU(time-shared, I/O switching)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 작업 스케줄러 | 디스크의 작업을 메모리에 적재할 순서를 결정하는 모듈 | 대기열에서 세탁물 순서를 정하는 관리자 |
| CPU 스케줄러 | 메모리에 적재된 프로세스 중 CPU를 할당할 대상을 선택하는 모듈 | 여러 가사 중 다음에 할 일을 고르는 판단 |
| 메모리 관리자 | 다중 프로그램의 주소 공간을 분리·보호하는 모듈 | 세탁·설거지 공간을 분리하여 혼선을 방지하는 것 |

> 요약: 작업 스케줄러·CPU 스케줄러·메모리 관리자가 다중프로그래밍을 실현함

## Ⅲ. 절차
```text
작업 선택 --> 메모리 적재 --> CPU 할당 --> I/O 대기 시 문맥 교환
```
- 1단계: 작업 스케줄러가 디스크 대기 큐에서 작업을 선택하여 메모리에 적재함
- 2단계: CPU 스케줄러가 준비 큐의 프로세스 중 하나를 선택하여 CPU를 할당함
- 3단계: 실행 중 I/O 요청이 발생하면 해당 프로세스를 대기 상태로 전환함
- 4단계: 문맥 교환을 수행하여 준비 큐의 다음 프로세스에 CPU를 재할당함

> 요약: 작업 적재-CPU 할당-I/O 전환-문맥 교환의 순환으로 CPU 이용률을 극대화함

## Ⅳ. 문제점
- 메모리 경합: 적재 프로그램 수 증가 시 프로세스당 가용 프레임이 부족해짐
- 문맥 교환 비용: 레지스터·PCB 저장/복원에 CPU 사이클이 소모됨
- 보호 위반 위험: 프로세스 간 주소 공간 격리가 미흡하면 타 프로세스 메모리를 침범함

> 요약: 메모리 경합, 문맥 교환 비용, 보호 위반이 다중프로그래밍의 주요 문제임

## Ⅴ. 개선방안
1. 단기: 워킹셋 기반 다중도 조절로 메모리 경합과 스래싱을 방지함 (018 참조)
2. 중기: 경량 문맥 교환(하드웨어 컨텍스트 스위치) 지원 프로세서를 활용하여 교환 비용을 절감함
3. 장기: 가상 메모리 + MMU 기반 하드웨어 보호로 프로세스 간 주소 공간을 완전 격리함 (016 참조)

> 요약: 다중도 조절, 경량 문맥 교환, 하드웨어 메모리 보호로 문제를 해결함

## Ⅵ. 전망
- 발전 방향: 멀티코어·하이퍼스레딩 환경에서 다중처리(multiprocessing)와 결합하여 병렬성이 확장됨
- 기술사적 판단: 다중프로그래밍은 시분할·가상화의 기반 원리로 현대 OS의 핵심 전제임
- 기술사 제언: 컨테이너·마이크로VM 등 경량 격리 기술과 연계하여 다중도 정책을 재설계할 필요
