# 📖 【암기용】 개념 완전 이해

> 목적: Neo4j 그래프 DB를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 노드와 관계를 1급 데이터로 저장하고 탐색하는 그래프 데이터베이스
- **왜 필요한가**: 추천, 사기 탐지, 지식 그래프, 영향도 분석은 데이터 자체보다 데이터 사이 연결이 핵심이다. 테이블 조인을 여러 번 반복하면 탐색 비용이 커지므로 관계를 직접 저장하는 그래프 DB가 필요하다.
- **핵심 직관**: 사람 명단 표보다 사람 사이 친구선이 그려진 관계망 지도를 직접 들고 탐색하는 방식임

## 깊이 이해
- **배경·문제의식**: 관계형 DB는 외래키와 조인으로 관계를 표현하지만, 3-hop 이상 탐색이나 가변 길이 경로 질의에서는 조인 수가 늘어난다. Neo4j는 노드, 관계, 속성을 저장하고 Cypher로 패턴 매칭 질의를 수행한다.
- **작동 원리**: 노드는 라벨과 속성을 갖고, 관계는 방향·타입·속성을 가진다. 인덱스로 시작 노드를 찾은 뒤 인접 관계를 따라 traversal하여 경로, 최단거리, 중심성 같은 결과를 계산한다.
- **비유**: 지하철 역 목록만 보는 것이 아니라, 환승선까지 연결된 노선도를 따라 목적지까지 가는 방식임
- **구체 예시**: 결제 사기 탐지에서 카드, 단말, IP, 계정을 노드로 두고 2-hop 내 공유 단말 5개 이상 패턴을 탐지해 의심 거래를 선별함
- **흔한 오해·주의점**: 그래프 DB는 모든 질의에 유리하지 않다. 단순 집계와 대량 스캔은 컬럼형 분석 DB가 적합하며, 그래프 DB는 관계 탐색이 질의 중심일 때 선택한다.

## 연결 개념
- 그래프 모델 - 노드·관계·속성 기반 표현
- Cypher - 패턴 매칭 질의 언어
- 지식 그래프 - 엔티티와 관계의 의미망

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: Neo4j 답안은 노드·관계 구조와 traversal 비용, 활용 업무를 비교축으로 제시해야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Neo4j는 property graph 모델과 Cypher 질의로 관계 탐색을 수행하는 그래프 DB임.
> 2. **가치**: 2~5 hop 관계 탐색, 추천, 사기 탐지, 영향도 분석에서 조인 반복 비용을 줄임.
> 3. **판단 포인트**: 시작 노드 선택도, 관계 타입 설계, traversal 깊이 제한, 그래프 알고리즘 비용을 함께 판단함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 그래프 DB 모델 이해 확인 | node, relationship, property, label | RDB ERD와 동일한 모델로 설명하지 않음 |
| 질의 처리 판단 확인 | 인덱스 시작점, traversal, Cypher | 모든 질의를 그래프 DB로 처리한다고 단정하지 않음 |
| 적용 업무 식별 확인 | 추천, fraud, IAM, knowledge graph | 단순 CRUD 사례만 제시하지 않음 |

> 요약: Neo4j 문제는 연결 중심 문제인지 판단하고 traversal 설계와 한계를 함께 써야 함.

## Ⅰ. 개요 및 필요성

- 개요: Neo4j는 그래프 데이터베이스이다.
- 배경: 복잡한 관계 탐색이 많은 업무에서는 조인 기반 질의가 길어지고 경로 분석 비용이 증가한다.
- 필요성: 노드와 관계를 직접 저장해 Cypher 패턴 매칭과 경로 탐색을 수행한다.

---

## Ⅱ. 구조 및 구성요소

```text
Domain Entity -> Node(Label, Property) -> Relationship(Type, Direction, Property) -> Graph Pattern
Query -> Index Seek -> Traversal -> Path/Score Result
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Node | 사람·계정·상품 등 엔티티 표현 | label, property 보유 |
| Relationship | 엔티티 간 관계 표현 | 방향, 타입, 속성 보유 |
| Cypher | 패턴 매칭 질의 | MATCH, WHERE, RETURN |
| Graph Algorithm | 중심성·커뮤니티·경로 계산 | hop 제한과 비용 관리 |

> 요약: Neo4j는 노드와 관계를 저장하고 Cypher 패턴으로 관계 경로를 탐색함.

---

## Ⅲ. 동작원리 및 흐름도

```text
Cypher Query -> Start Node Index Seek -> Relationship Traversal -> Path Filter -> Result Projection
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 라벨·속성 인덱스로 시작 노드 탐색 | index seek 사용 여부 |
| 2 | 관계 타입과 방향 기준으로 확장 | expanded relationship count |
| 3 | hop 수와 조건으로 경로 필터링 | max depth, row count |
| 4 | 경로·점수·노드 결과 반환 | query latency p95 |
| 5 | 필요 시 그래프 알고리즘 실행 | memory estimate, job time |

> 요약: Neo4j 질의는 좋은 시작점을 잡고 관계를 제한적으로 확장해야 탐색 비용을 통제할 수 있음.

---

## Ⅳ. 특징

| 구분 | 관계형 DB | Neo4j | 판단 포인트 |
|:---|:---|:---|:---|
| 관계 표현 | 외래키·조인 | 관계 레코드 직접 저장 | 3-hop 이상 탐색 빈도 |
| 질의 방식 | SQL 조인 | Cypher 패턴 매칭 | 경로·패턴 중심 문제 |
| 분석 범위 | 집계·정렬 | 경로·중심성·커뮤니티 | 그래프 알고리즘 필요 여부 |

> 요약: Neo4j는 연결 탐색 문제에 적합하며, 대량 집계는 컬럼형 분석 DB와 분리한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | RDB 조인 테이블 | property graph | 관계 타입 5개 이상, 가변 hop 질의 |
| 비용/성능 | 다중 self-join | 인접 관계 traversal | 시작 노드 선택도 1% 이하 |
| 운영/위험 | SQL 튜닝 | 그래프 모델·경로 제한 | 무제한 traversal 금지 |

> 요약: Neo4j는 관계 깊이와 패턴 질의가 핵심 요구일 때 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 탐색 폭증 | 고차수 노드 중심 확장 | 관계 타입·hop 제한 | expanded relationships |
| 모델 오염 | 모든 속성을 노드화 | 엔티티/속성 구분 규칙 | node/relationship 증가율 |
| 분석 지연 | 대규모 알고리즘 실행 | 배치 그래프 분석, 샘플링 | algorithm job time |

> 요약: Neo4j 리스크는 탐색 범위, 모델링 기준, 알고리즘 실행 비용으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 질의 | p95 query latency 100ms 이하 | PROFILE, query log |
| 탐색 | max hop 2~5 명시 | Cypher plan 검토 |
| 모델 | 고차수 노드 top 1% 관리 | degree distribution 분석 |

> 요약: Neo4j 적용 효과는 질의 지연, hop 제한, 노드 차수 분포로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 업무 질문을 "누가 누구와 몇 hop으로 연결되는가" 형태로 정의한 뒤 노드·관계·속성 경계를 고정함.
2. Cypher는 시작 노드 인덱스, 관계 타입, hop 상한을 명시하고 PROFILE로 full graph scan을 제거함.
3. 추천·사기 탐지는 온라인 질의와 배치 그래프 알고리즘을 분리하고 결과 점수는 캐시·검색 계층에 배포함.

**결론 (2줄):**
- 기술사 판단: 관계 탐색이 업무 가치이면 Neo4j, 단순 집계·대량 스캔이면 분석 DB를 선택함.
- 향후 방향: 그래프 DB는 지식 그래프, RAG, 권한 그래프와 결합되어 의미 기반 탐색 계층으로 확대됨.
