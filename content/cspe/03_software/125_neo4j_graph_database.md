## 미리 알고가기

- 그래프 DB는 데이터를 정점과 관계로 저장해 연결 자체를 1급 객체처럼 다루는 DB임
- Neo4j는 속성 그래프 모델을 사용해 노드와 관계에 각각 속성을 붙일 수 있음
- Cypher는 패턴 매칭 중심으로 그래프를 조회하는 Neo4j 질의 언어임

## Ⅰ. 개요

- **정의/개념**: Neo4j는 사람·계정·거래·추천 대상처럼 연결 관계가 핵심인 데이터를 노드와 관계와 속성으로 저장하고 패턴 탐색을 빠르게 수행하는 그래프 데이터베이스임
- **배경/필요성**: 추천, 사기 탐지, 네트워크 경로 분석처럼 조인 깊이가 계속 늘어나는 문제는 관계형 조인보다 그래프 탐색이 더 직접적이어서 그래프 DB가 필요해짐

## Ⅱ. 특징

- 관계를 별도 테이블 조인 없이 직접 따라갈 수 있어 연결 탐색에 강함
- 노드와 관계 모두에 속성을 붙여 현실 객체와 관계를 함께 표현하기 좋음
- Cypher로 경로와 패턴을 읽기 쉬운 형태로 질의할 수 있음
- 대량 집계나 단순 스캔 위주 업무는 일반 관계형 DB보다 유리하지 않을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB | Neo4j |
|:---|:---|:---|
| 모델 중심 | 테이블과 조인 중심 | 노드와 관계 중심 |
| 강한 영역 | 정합성 높은 업무 처리와 집계 | 경로 탐색과 추천과 연관 분석 |
| 성능 병목 | 조인 깊이가 깊어질수록 비용이 커짐 | 광범위 스캔과 대량 집계는 비효율적일 수 있음 |
| 적합 데이터 | 구조가 고정된 업무 데이터 | 연결 구조가 자주 쓰이는 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Node | 사람, 상품, 계정 같은 개체를 표현함 |
| Relationship | 개체 사이의 연결과 방향과 의미를 표현함 |
| Property | 노드와 관계의 세부 속성을 담음 |
| Label / Index | 탐색 시작점을 좁히고 조회 속도를 높임 |
| Cypher Engine | 패턴 매칭과 경로 탐색 질의를 수행함 |

```text
(User)-[BOUGHT]->(Product)-[IN_CATEGORY]->(Category)
      \-[FOLLOWS]->(User)
```

## Ⅴ. 원리 및 절차 흐름도

```text
개체 식별 -> 관계 모델링 -> 노드/간선 저장 -> 패턴 질의 -> 경로 분석
```

1. **개체 식별**: 사람과 상품과 계정 같은 핵심 노드를 정함
2. **관계 모델링**: 연결 방향과 의미와 속성을 정의함
3. **저장과 색인**: 노드와 관계를 저장하고 시작점 인덱스를 둠
4. **패턴 질의**: Cypher로 필요한 연결 패턴을 찾음
5. **경로 분석**: 추천과 탐지와 연관 관계 분석에 활용함

## Ⅵ. 실무 적용 및 유의점

1. 추천과 사기 탐지처럼 관계를 여러 단계 따라가야 하는 서비스는 Neo4j가 유리하지만 관계 타입과 방향을 모호하게 두면 질의가 곧 복잡해지므로 모델 규칙을 먼저 정하고 평균 경로 탐색 시간과 질의 복잡도 증가율로 확인함
2. 그래프 DB를 도입해도 모든 데이터를 옮기기보다 연결 분석이 핵심인 영역부터 분리하고 그래프 질의 비율과 배치 동기화 지연과 운영 복잡도로 확인함

## Ⅶ. 결론

- Neo4j는 연결 자체가 핵심인 문제를 직접 풀게 해 주는 DB이므로 관계 모델링 규칙과 적용 범위를 분명히 할수록 효과가 커짐
