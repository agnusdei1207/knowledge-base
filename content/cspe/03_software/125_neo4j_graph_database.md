## 미리 알고가기

- 그래프 DB는 노드(Node, 정점)와 관계를 저장해 연결 자체를 조회 대상으로 다루는 데이터베이스임
- 속성 그래프는 노드와 방향성 관계에 레이블·유형·속성을 부여하는 데이터 모델임
- Cypher는 노드·관계 패턴과 가변 길이 경로를 선언하는 Neo4j 질의 언어임
- 시작 노드 인덱스는 탐색 대상을 좁히고, 인접 관계는 현재 노드에서 다음 노드로 확장하는 경로가 됨

## 작성 근거(검토용)

- Neo4j는 속성 그래프, 인접 관계 탐색, Cypher 패턴, 인덱스·제약, 경로 확장 비용을 핵심 축으로 설명함
- 비교표는 관계형 DB와 관계 저장·질의·비용 증가 요인·적합 데이터의 차이를 같은 기준에서 대비함
- 실무 사례는 권한 관계와 서비스 의존 그래프에서 경로 질의 지연·고아 관계로 검증함

## Ⅰ. 개요

- **정의/개념**: Neo4j는 노드·방향성 관계·속성을 저장하고 Cypher 패턴으로 다단계 연결과 경로를 탐색하는 속성 그래프 데이터베이스임
- **배경/필요성**: 권한 상속·서비스 의존성·사기 거래처럼 관계의 깊이와 경로 자체가 질의 결과일 때 반복 조인을 줄이기 위해 관계 중심 저장·탐색 구조가 필요함

## Ⅱ. 특징

- 현재 노드의 인접 관계를 따라 다음 노드로 확장해 관계 테이블의 반복 조인을 줄임
- 노드 레이블과 관계 유형·방향·속성으로 개체와 연결 의미를 함께 표현함
- Cypher의 패턴·경로 문법으로 고정 길이와 가변 길이 연결을 선언함
- 탐색 시작점이 넓거나 관계 분기 수·경로 깊이가 커지면 후보 경로와 메모리 사용량이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB | Neo4j |
|:---|:---|:---|
| 데이터 모델 | 행·테이블·외래키 | 노드·레이블·방향성 관계·속성 |
| 관계 저장 | 외래키 값과 관계 테이블로 연결 | 노드에서 인접 관계를 따라갈 수 있게 연결을 저장 |
| 질의 방식 | 조건 검색·조인·집계 | Cypher의 노드·관계 패턴과 경로 확장 |
| 비용 증가 요인 | 조인 대상 행 수·조인 순서·중간 결과 크기 | 시작 노드 수·관계 분기 수·탐색 깊이 |
| 무결성 통제 | 기본키·외래키·테이블 제약 | 레이블별 속성 제약·고유성 제약·애플리케이션 관계 규칙 |
| 적합 조건 | 정형 관계·집계·다중 행 처리가 중심인 데이터 | 다단계 연결·경로·이웃 관계가 질의 결과인 데이터 |

> 요약: 관계형 DB는 외래키 조인으로 관계를 계산하고, Neo4j는 저장된 인접 관계를 Cypher 경로로 확장함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 노드·레이블 | 개체를 저장하고 레이블로 노드 집합과 적용 제약을 구분함 |
| 관계·유형·방향 | 두 노드를 연결하고 관계 의미와 탐색 방향을 표현함 |
| 속성 | 노드와 관계의 식별자·상태·가중치 정보를 저장함 |
| 인덱스·제약 | 시작 노드를 찾고 속성 존재·고유성 규칙을 검사함 |
| Cypher 실행기 | 패턴을 연산자로 변환하고 인덱스 탐색·관계 확장·필터를 수행함 |

```text
(사용자)-[구매]->(상품)-[분류]->(카테고리)
        \-[팔로우]->(사용자)
```

> 요약: 노드 레이블과 관계 유형·방향이 그래프 구조를 만들고 인덱스와 Cypher 실행기가 시작점부터 경로를 확장함.

## Ⅴ. 원리 및 절차 흐름도

```text
Cypher 수신 -> 시작 노드 탐색 -> 관계 확장 -> 조건·경로 판정 -> 결과 반환
```

1. **Cypher 수신**: 질의의 노드 레이블·관계 유형·방향·경로 조건을 해석함
2. **시작 노드 탐색**: 인덱스 또는 레이블 스캔으로 첫 노드 집합을 찾음
3. **관계 확장**: 지정한 유형·방향·깊이에 따라 인접 관계를 순회함
4. **조건·경로 판정**: 노드·관계 속성 조건을 적용하고 후보 경로를 제한함
5. **결과 반환**: 일치한 노드·관계·경로 또는 집계 결과를 반환함

> 요약: Neo4j는 인덱스로 시작 노드를 찾고 관계 유형·방향·깊이에 따라 경로를 확장해 Cypher 결과를 만듦.

## Ⅵ. 실무 사례

1. 접근 권한 분석은 계정·역할·자원 관계의 방향을 정의하고 p95 경로 질의 지연·비인가 권한 경로 수를 확인함
2. 서비스 영향 분석은 호출 관계 유형과 탐색 깊이를 제한하고 p95 탐색 지연·누락 관계 건수를 확인함

## Ⅶ. 결론

- Neo4j는 관계 유형·방향·분기 수·탐색 깊이와 경로 질의 비중을 기준으로 적용해야 함
