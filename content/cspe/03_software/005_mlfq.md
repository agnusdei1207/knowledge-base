## Ⅰ. 개요
- 정의: 우선순위가 다른 여러 개의 큐를 두고, 프로세스 특성에 따라 큐 사이를 이동시키는 기법
- 배경: 작업의 CPU 집중/IO 집중 성격을 사전에 알기 어려운 환경에서 적응적 대응 필요
- 출제 의도: 대화형 작업과 CPU 집약 작업을 실행 이력으로 구분하는 스케줄링 원리 이해

## Ⅱ. 구성요소
```
Q0 (RR 8ms)  ----[ Demote ]----> Q1 (RR 16ms) ----[ Demote ]----> Q2 (FCFS)
      |                          |                         |
[ New Process ]            [ Time Out ]              [ Completion ]
```
| 구성요소 | 설명 | 판단 기준 |
| :--- | :--- | :--- |
| 다단계 큐 | 서로 다른 타임 슬라이스를 가진 큐의 집합 | 대기열별 실행 시간 |
| 피드백 | 실행 결과에 따라 우선순위 큐를 변경하는 메커니즘 | CPU 사용 이력 |
| 우선순위 상향 | 기아 방지를 위해 일정 시간 후 상위 큐로 이동 | 장기 대기 시간 |
> 요약: 실행 이력을 바탕으로 프로세스를 적절한 우선순위 큐로 재배치함.

## Ⅲ. 절차
```
[Entry] -> [Q0 실행] -> [Time Out 시 Q1 이동] -> [Q1 실행] -> [FCFS 큐 안착]
```
1. 모든 신규 프로세스는 가장 높은 우선순위 큐(Q0)에 진입함
2. 할당 시간 내 작업을 못 끝낸 CPU 집약적 작업은 하위 큐로 강등(Demote)됨
3. I/O 대기 후 복귀하는 대화형 작업은 높은 우선순위를 유지하여 응답성 확보
4. 주기적으로 모든 프로세스를 최상위 큐로 이동(Priority Boost)시켜 기아 방지
> 요약: 최근 실행 이력에 따라 큐를 조정해 응답성과 장기 대기를 함께 다룸.

## Ⅳ. 문제점
- 원인: 하위 큐의 프로세스가 상위 큐 작업에 밀려 실행 기회를 얻지 못함(Starvation)
- 원인: 큐 간 이동 및 복잡한 관리 로직으로 인한 스케줄러 자체의 부하 발생함

## Ⅴ. 개선방안
- (단기) 에이징(Aging) 또는 주기적 우선순위 상향(Boosting) 정책 강제 적용
- (중기) 워크로드 분석을 통한 큐 개수 및 타임 슬라이스 값의 동적 튜닝
- (장기) 리눅스의 CFS와 같은 공정성 기반 스케줄러와 혼합하여 하이브리드 운영

## Ⅵ. 전망
- 분산 작업 스케줄러에서도 실행 시간과 대기 시간을 이용한 단계별 큐 정책이 활용됨
- 대규모 연산 환경에서는 큐별 타임 슬라이스와 우선순위 조정이 처리 지연 관리 지표가 됨

## 작성 근거(검토용)

- MLFQ는 자동 학습 알고리즘이 아니라 실행 이력에 따라 큐를 이동시키는 정책이므로 표현을 절차 중심으로 고침
- 전망도 AI 구현 단정 대신 큐별 타임 슬라이스, 우선순위 조정, 처리 지연으로 판단 기준을 명시함
