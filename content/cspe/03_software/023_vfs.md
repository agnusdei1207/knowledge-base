## Ⅰ. 개요
- 정의: 서로 다른 파일 시스템들을 동일한 인터페이스로 접근할 수 있게 해주는 추상화 계층
- 배경: 이기종 파일 시스템(EXT4, NFS, FAT 등)을 투명하게 지원하여 사용자 편의성 제공
- 출제 의도: 다형성(Polymorphism) 기반의 파일 인터페이스 구현 및 객체 모델 이해

## Ⅱ. 구성요소
```
[ User App (open/read/write) ]
              |
[ VFS Layer (Common Interface) ]
    /         |         \
 [EXT4]    [FAT32]    [NFS]
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Superblock | 파일 시스템 전체 정보를 담는 객체 | 도서관 정보 |
| Inode | 개별 파일의 고유 식별 정보 및 속성 | 도서 명세 |
| Dentry | 디렉터리 계층 구조와 파일명을 연결 | 도서 분류함 |
| File | 실행 중인 프로세스가 파일을 사용하는 관점의 객체 | 대출한 책 |
> 요약: 객체 지향적 접근을 통해 다양한 파일 시스템의 차이를 은폐함.

## Ⅲ. 절차
```
[App Syscall] -> [VFS Entry] -> [Function Pointer Check] -> [FS Driver Call]
```
1. 애플리케이션이 표준 시스템 호출(예: read)을 호출함
2. VFS는 호출된 파일 객체의 `file_operations` 구조체 내 함수 포인터 확인
3. 등록된 특정 파일 시스템(예: EXT4)의 실제 읽기 구현 함수로 제어 이양
4. 하위 드라이버에서 데이터 처리 후 결과를 역순으로 반환
> 요약: 공통 인터페이스가 함수 포인터를 통해 실제 구현체로 작업을 전달함.

## Ⅳ. 문제점
- 원인: 계층화 및 추상화로 인한 호출 경로 복잡화 및 성능 오버헤드 미세 발생
- 원인: 특정 파일 시스템 전용 특수 기능(Extended Attr 등) 반영 시 인터페이스 제약 발생

## Ⅴ. 개선방안
- (단기) 자주 참조되는 dentry와 inode 정보를 캐싱(Dcache, Icache)하여 성능 보완
- (중기) `ioctl`이나 `fcntl` 등을 활용하여 파일 시스템 특화 기능 확장 통로 확보
- (장기) FUSE(Filesystem in Userspace)를 활용하여 사용자 공간에서 유연한 FS 구현 지원

## Ⅵ. 전망
- 컨테이너 환경의 오버레이 파일 시스템(OverlayFS) 등 논리적 계층 구조 관리의 핵심 기술로 유지
- 하드웨어 가속 스토리지 및 네트워크 직접 접근(RDMA) 환경에 대응하는 초고속 VFS 진화 예상
