## Ⅰ. 개요
- 정의: 데이터베이스의 목표 처리량과 응답 시간을 충족하도록 파라미터, 인덱스, SQL을 조정하는 활동
- 배경: 응답 지연과 CPU·메모리·디스크 I/O 병목 해소
| 구분 | 내용 |
|------|------|
| 출제 의도 | DB 디자인, 인덱스, SQL 작성, 서버 설정 등 계층별 튜닝 포인트 이해 |

## Ⅱ. 구성요소
  [ SQL Tuning ] <- [ Index Tuning ] <- [ Server Tuning ]
  (Low Impact)     (Medium Impact)     (High Impact)
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| Execution Plan | 옵티마이저가 수립한 쿼리 실행 경로 정보 | 항로 지도 |
| Hint | 옵티마이저에게 특정 경로를 강제하는 지시어 | 가이드라인 |
| Wait Event | 시스템 병목의 원인이 되는 대기 현상 지표 | 정체 신호 |
> 요약: 실행 계획과 대기 이벤트로 병목을 식별하고 SQL·인덱스·서버 설정을 조정함

## Ⅲ. 절차
  Monitor -> Analyze -> Plan -> Execute -> Evaluate
1. Monitoring: Slow Query Log 및 성능 뷰를 통한 부하 분석
2. Analysis: 실행 계획 확인 및 병목(Full Scan 등) 지점 파악
3. Optimizing: 인덱스 추가, 쿼리 재작성, 파티셔닝 적용
4. Testing: 운영 환경 반영 전 성능 개선 효과 검증
> 요약: 변경 전후 응답 시간·처리량·자원 사용률을 비교하여 튜닝 효과를 검증함

## Ⅳ. 문제점
- 부분적 튜닝이 다른 쿼리의 성능을 저하시키는 사이드 이펙트
- 통계 데이터 미갱신으로 인한 옵티마이저의 잘못된 판단

## Ⅴ. 개선방안
- 통계 정보 자동 업데이트 주기 설정 및 힌트 사용 최소화
- 애플리케이션 설계 단계부터 SQL 성능 가이드라인 준수

## Ⅵ. 전망
- 머신러닝 기반 자동 인덱스 선정 및 자율 운영(Autonomous) DB 기술 보편화
