# 📖 【암기용】 개념 완전 이해

> 목적: MDM을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 고객, 상품, 조직처럼 여러 시스템이 공유하는 기준 데이터를 하나의 신뢰 원천으로 관리하는 체계
- **왜 필요한가**: 같은 고객이 CRM, ERP, 쇼핑몰에 서로 다른 이름과 주소로 존재하면 매출 집계, 배송, 마케팅, 규제 대응이 흔들린다.
- **핵심 직관**: 주민등록 원장처럼 핵심 식별자와 속성의 기준본을 정해 각 업무 시스템이 같은 대상을 같은 의미로 쓰게 한다.

## 깊이 이해
- **배경·문제의식**: 업무 시스템은 도입 시점과 목적이 달라 고객, 상품, 공급사 코드가 중복된다. MDM은 식별, 매칭, 병합, golden record 생성, 배포 절차로 기준 데이터를 정리한다.
- **작동 원리**: 원천 시스템에서 마스터 후보를 수집하고, 표준화와 중복 탐지를 수행한다. 규칙 기반 또는 확률 기반 매칭으로 동일 대상을 묶고, survivorship rule로 대표 속성을 정해 golden record를 만든다.
- **비유**: 여러 주소록을 합쳐 하나의 공식 연락처를 만드는 일과 같다. 전화번호는 A 주소록, 주소는 B 주소록, 동의 여부는 C 시스템을 기준으로 삼을 수 있다.
- **구체 예시**: 고객 MDM에서 이름+휴대폰+생년월일 매칭 점수 0.92 이상이면 동일 고객 후보로 묶고, 휴대폰은 본인인증 시스템 값을 기준 속성으로 채택한다.
- **흔한 오해·주의점**: MDM은 단순 중복 제거가 아니다. 데이터 모델, 오너, 승인, 배포, 변경 이력까지 포함한 운영 체계다.

## 연결 개념
- 데이터 품질 관리 - 표준화, 중복률, 정확도 측정
- 데이터 거버넌스 - master owner와 승인 정책 제공
- 데이터 카탈로그 - 마스터 데이터 정의와 사용처 제공

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: MDM 답안은 고객/상품/조직 기준 데이터의 식별, 매칭, golden record, 배포, 거버넌스를 한 흐름으로 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MDM은 기업 핵심 기준 데이터를 식별, 정제, 중복 제거, golden record 생성, 배포로 관리하는 체계임.
> 2. **가치**: 고객 중복률, 상품 코드 불일치, 조직 기준 오류를 정량 지표로 낮춰 보고와 업무 처리를 같은 기준으로 맞춤.
> 3. **판단 포인트**: Registry, Consolidation, Coexistence, Centralized 패턴 중 업무 변경 권한과 실시간 요구에 맞춰 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기준 데이터 정합성 이해 확인 | 식별자, 매칭, 병합, golden record | 중복 제거만 서술 |
| 아키텍처 패턴 판단 확인 | Registry, Consolidation, Coexistence, Centralized | 모든 시스템을 중앙 DB로 단정 |
| 운영 통제 확인 | master owner, 변경 승인, 배포, 감사 | 거버넌스 누락 |

> 요약: MDM은 기준 데이터의 기술 처리와 업무 책임을 함께 설계하는 문제가 핵심임.

## Ⅰ. 개요 및 필요성

- 개요: MDM은 기준 데이터의 신뢰 원천 관리 체계임.
- 배경: 고객, 상품, 공급사, 조직 데이터가 시스템별로 불일치하면 집계 오류와 업무 처리 지연이 발생한다.
- 필요성: golden record와 배포 절차로 고객, 상품, 조직 등 기업 공통 기준 데이터를 제공한다.

---

## Ⅱ. 구조 및 구성요소

```text
Source Systems -> Standardization -> Match/Merge -> Golden Record -> Publish/API
                               +-> Steward Review
                               +-> Audit History
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 원천 시스템 | CRM, ERP, 쇼핑몰, 콜센터 데이터 제공 | source priority 필요 |
| 표준화 | 이름, 주소, 코드, 형식 정리 | 주소 표준, 코드 표준 |
| 매칭/병합 | 동일 대상 후보 식별과 중복 제거 | rule/probabilistic match |
| Golden Record | 대표 속성 기준본 생성 | survivorship rule 적용 |
| 배포/API | 업무 시스템에 기준 데이터 제공 | CDC, REST, message |

> 요약: MDM은 원천 수집, 표준화, 매칭, 기준본 생성, 배포로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
수집 -> 표준화 -> 중복 후보 산정 -> steward 승인 -> golden record 생성 -> 하위 시스템 배포
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원천 데이터 수집과 식별자 추출 | source coverage 95% 이상 |
| 2 | 주소, 코드, 전화번호 표준화 | 형식 오류율 1% 이하 |
| 3 | 매칭 점수 산정과 병합 후보 생성 | match precision 95% 이상 |
| 4 | steward 승인과 예외 처리 | 승인 SLA 2일 이하 |
| 5 | golden record 배포와 이력 관리 | 배포 지연 5분 이하 |

> 요약: MDM은 자동 매칭과 steward 승인을 결합해 기준 데이터를 만들고 배포함.

## Ⅳ. 특징

| 구분 | 시스템별 기준 관리 | MDM | 판단 포인트 |
|:---|:---|:---|:---|
| 식별 | 업무 시스템별 ID | enterprise key | 고객 중복률 |

| 변경 | 시스템별 수정 | 승인 후 배포 | 배포 지연 5분 이하 |

> 요약: MDM은 기준 데이터 일치를 위해 기술 매칭보다 업무 기준 합의가 선행되어야 함.

> 요약: MDM은 중복률과 기준 오류가 업무 비용으로 이어지는 도메인부터 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |

> 요약: MDM 성과는 중복률, 매칭 정확도, 배포 지연으로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 도메인 선정: 고객, 상품, 조직 중 중복률 3% 이상 또는 규제 보고 대상 도메인을 1차 범위로 선정
2. 매칭 설계: 이름, 휴대폰, 생년월일, 주소 정규화 후 match score 0.92 이상 자동 병합, 0.80~0.92 steward 검토
3. 배포 통제: golden record 변경은 CDC/API로 5분 이내 배포하고 변경 전후 값을 1년 이상 감사로그로 보관

**결론 (2줄):**
- 기술사 판단: 기준 데이터 오류가 매출, 배송, 규제 보고에 영향을 주면 MDM을 도입하고 단순 분석용 중복은 DQ 규칙으로 처리함
- 향후 방향: MDM은 데이터 제품, 고객 360, AI 피처 관리의 기준 데이터 허브로 확장됨
