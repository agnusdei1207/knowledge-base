## Ⅰ. 개요
- **정의**: 사람의 반복적 PC 조작을 SW 로봇이 모방·자동 수행하는 업무 자동화 기술임
- **배경/필요성**: 규칙 기반 반복 업무에 인력을 투입하는 비효율을 해소할 자동화 수단이 필요함
- **비유**: 매크로 녹화처럼 사람의 마우스·키보드 조작을 로봇이 대신 재생하는 것임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| RPA 적용 범위와 한계 | Attended vs Unattended 구분 | BPM·AI와의 관계(Hyperautomation 맥락) |

> 요약: 규칙 기반 반복 업무를 SW 로봇으로 자동화하는 기술임

## Ⅱ. 구성요소
```text
RPA Platform
  +-- Bot Designer (설계 도구)
  |     +-- 워크플로 녹화/편집
  +-- Bot Runner (실행 엔진)
  |     +-- Attended Bot / Unattended Bot
  +-- Orchestrator (관리 서버)
        +-- 스케줄링 / 모니터링 / 로그 관리
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Bot Designer | 자동화 워크플로를 녹화·편집하는 개발 도구 | 매크로 녹화기 |
| Bot Runner | 설계된 워크플로를 실행하는 SW 로봇 엔진 | 녹화된 매크로 재생기 |
| Orchestrator | 다수 봇의 스케줄·실행·모니터링을 관리하는 중앙 서버 | 로봇 관제탑 |

> 요약: 설계-실행-관리 3계층으로 봇 자동화 플랫폼이 구성됨

## Ⅲ. 절차
```text
업무 분석/선정 --> 워크플로 설계 --> 봇 개발/테스트 --> 배포/운영/모니터링
```
- 1단계: 자동화 대상 업무를 선정하고 ROI·적합성(규칙성·반복성·안정성)을 평가함
- 2단계: 대상 업무의 단계별 조작을 워크플로로 설계하고 예외 처리를 정의함
- 3단계: Bot Designer로 봇을 개발하고 테스트 데이터로 정상·예외 케이스를 검증함
- 4단계: Orchestrator에 봇을 배포하고 실행 로그·성공률을 모니터링함

> 요약: 업무 선정부터 운영 모니터링까지 4단계로 수행함

## Ⅳ. 문제점
- UI 의존 취약성: 대상 시스템 UI 변경 시 — 봇이 동작 불능 상태에 빠짐
- 예외 처리 한계: 비정형·판단 필요 업무 — 규칙 기반 봇으로는 대응이 불가함
- 봇 난립: 부서별 무분별 봇 생성 — 유지보수 부담과 보안 위험이 증가함

> 요약: UI 의존성·비정형 업무 한계·봇 관리 부재가 핵심 문제임

## Ⅴ. 개선방안
1. 단기: API 연동 방식을 병행하여 UI 변경에 대한 봇 취약성을 줄임
2. 중기: AI/ML 기반 문서 인식·의사결정을 결합하여 비정형 업무 대응력을 확보함
3. 장기: CoE 기반 봇 거버넌스(등록·인증·폐기 정책)를 수립하여 전사 관리 체계를 구축함

> 요약: API 연동, AI 결합, 거버넌스 체계 순으로 개선함

## Ⅵ. 전망
- 발전 방향: AI·프로세스마이닝과 결합한 Hyperautomation으로 확장 중임
- 기술사적 판단: 단순 업무 자동화에서 지능형 업무 자동화로 진화가 가속됨
- 기술사 제언: RPA 단독 도입보다 BPM·AI와 통합한 자동화 로드맵을 수립할 것을 권고함
