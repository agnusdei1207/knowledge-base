## Ⅰ. 개요
- 정의: 개발(Dev)과 운영(Ops)의 협업을 통해 S/W 품질 향상 및 배포 속도를 높이는 문화이자 기술.
- 출제 의도: 가치 전달 가속화를 위한 자동화 파이프라인과 지속적 피드백 체계의 핵심 가치 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Plan ] -> [ Code ] -> [ Build ] -> [ Test ] --+
     ^                                            | (CI)
     |                                            v
  [ Monitor ] <- [ Operate ] <- [ Deploy ] <- [ Release ]
     (Feedback)                   (CD)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| CI (지속 통합) | 코드 변경을 자동 빌드 및 테스트하여 공유 저장소 통합 | 정기적 건강 검진 |
| CD (지속 배포) | 검증된 코드를 운영 환경에 자동 배포하는 프로세스 | 자동 택배 시스템 |
| 자동화 | 인프라, 테스트, 모니터링 등 반복 작업을 코드로 처리 | 로봇 조립 라인 |
> 요약: 사람의 개입을 줄이고 자동화된 검증을 통해 배포 신뢰성을 확보함.

## Ⅲ. 절차
- ASCII 흐름도
  [Code Push] -> [Build & Lint] -> [Unit Test] -> [Artifact Deploy]
- 4단계 설명
1. 개발자가 기능을 구현하여 소스 제어 시스템(Git)에 코드를 커밋함.
2. CI 서버가 감지하여 컴파일, 정적 분석 및 종속성 해결 자동 수행함.
3. 사전에 작성된 단위/통합 테스트를 실행하여 결함 조기 발견함.
4. 모든 검증 통과 시 운영 서버나 스테이징 환경에 즉시 반영함.
> 요약: 작고 빈번한 릴리즈를 통해 변경에 따른 리스크를 분산함.

## Ⅳ. 문제점
- 문화적 저항: 사일로(Silo) 현상으로 인해 개발과 운영 팀 간의 책임 전가 및 소통 단절됨.
- 파이프라인 과부하: 테스트 케이스 증가 시 배포 시간이 길어져 민첩성 저하됨.

## Ⅴ. 개선방안
- Shared Responsibility: 장애 발생 시 공동 책임 문화를 조성하고 보상 체계 연동함.
- 병렬 테스트: 컨테이너 기술을 활용해 테스트를 병렬 실행하여 피드백 속도 단축함.

## Ⅵ. 전망
- 보안이 통합된 DevSecOps로 진화하여 개발 초기 단계부터 보안 취약점 자동 차단함.
- ML/AI가 적용된 MLOps 프레임워크와 결합하여 데이터 모델 배포 자동화 주도함.
- 플랫폼 엔지니어링의 확산으로 개발자가 셀프 서비스로 인프라를 이용하는 환경으로 고도화됨.
