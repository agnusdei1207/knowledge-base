## Ⅰ. 개요
- 정의: 컨테이너화된 애플리케이션의 배포, 확장, 관리를 자동화하는 오픈소스 플랫폼.
- 출제 의도: 대규모 컨테이너 운영 환경에서 필수적인 선언적 구성 및 자가 치유 기능 이해도 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Control Plane ] <--- [ kubectl ]
       | (Manage)
  [ Node 1 ] [ Node 2 ] [ Node 3 ]
  ( Pods )   ( Pods )   ( Pods )
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 컨트롤 플레인 | 클러스터의 상태를 결정하고 노드를 관리하는 뇌 역할 | 관제탑 |
| 노드 (Worker) | 실제 컨테이너(Pod)가 실행되는 서버 호스트 | 활주로 |
| 오브젝트 | 클러스터의 상태를 나타내는 엔티티(Pod, Service 등) | 항공기/화물 |
> 요약: 선언적 API를 통해 사용자가 원하는 상태(Desired State)를 유지하도록 관리함.

## Ⅲ. 절차
- ASCII 흐름도
  [Manifest 정의] -> [API 서버 요청] -> [스케줄링] -> [실행 및 모니터링]
- 4단계 설명
1. YAML 파일에 원하는 리소스 상태를 기술하여 kubectl로 제출함.
2. 컨트롤러 매니저가 현재 상태와 희망 상태의 차이를 감지함.
3. 스케줄러가 자원 여유가 있는 최적의 노드에 Pod 할당함.
4. Kubelet이 컨테이너를 실행하고 상태를 지속적으로 피드백함.
> 요약: '원하는 상태'를 선언하면 시스템이 자동으로 일치시키는 제어 루프 구조임.

## Ⅳ. 문제점
- 높은 학습 곡선: 복잡한 아키텍처와 방대한 객체 종류로 인해 초기 도입 및 운영 난이도 높음.
- 네트워크 복잡성: 오버레이 네트워크 구성 및 서비스 간 통신 보안 설정이 까다로움.

## Ⅴ. 개선방안
- 관리형 서비스(EKS, GKE, AKS): 클라우드 벤더의 관리형 K8s 도입으로 운영 부담 경감 필요함.
- GitOps 도입: ArgoCD 등 도구를 사용하여 클러스터 상태를 Git 소스와 동기화하여 관리 표준화함.

## Ⅵ. 전망
- 쿠버네티스가 '클라우드의 운영체제(Cloud OS)'로 자리매김하며 사실상 업계 표준(De-facto Standard) 확정됨.
- AI/ML 워크로드를 위한 Kubeflow 등 특화 프레임워크와의 결합 가속화될 것임.
- 멀티 클라우드 및 엣지 컴퓨팅 확장에 따라 연합(Federation) 및 경량 K8s(K3s) 활용 사례 증대됨.
