## 미리 알고가기

- 완전성(Completeness)은 업무에 필요한 레코드·속성값이 누락되지 않은 정도임
- 정확성(Accuracy)은 데이터 값이 신뢰 기준이나 실제 업무 사실과 일치하는 정도임
- 일관성(Consistency)은 시스템·테이블·시점 사이에서 같은 개체와 규칙의 값이 모순되지 않는 정도임
- 데이터 프로파일링은 분포·Null·중복·범위·패턴을 계산해 품질 규칙 후보와 이상을 찾음
- 품질 규칙은 대상 열·판정 조건·허용 임계값·책임자·위반 처리 방식을 정의함
- 격리 영역은 규칙을 통과하지 못한 레코드와 위반 사유를 정상 처리 경로에서 분리함

## 작성 근거(검토용)

- 문제 제목의 완전성·정확성·일관성을 정의·규칙·측정·교정으로 끝까지 연결함
- 비교표는 세 품질 차원의 질문·검사·실패·지표·조치를 동일 수준에서 대비함
- 절차는 프로파일링부터 규칙 실행·격리·원인 배정·재측정까지 품질 상태 변화를 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 품질 차원의 의미를 혼용하지 않음

## Ⅰ. 개요

- **정의/개념**: 데이터 품질 관리는 사용 목적에 맞춰 완전성·정확성·일관성 규칙과 허용 임계값을 정의하고 측정·격리·원인 조치·재검증하는 관리 활동임
- **배경/필요성**: 누락·오류·시스템 간 모순이 분석과 응용 판단에 전파되지 않도록 데이터 생산 지점부터 품질 상태를 판정할 기준이 필요함

## Ⅱ. 특징

- 데이터 사용 목적과 중요 데이터 요소별로 품질 차원·규칙·허용 임계값을 다르게 설정함
- 프로파일링 결과로 Null·범위·패턴·중복·참조 분포를 확인하고 규칙의 기준선을 정함
- 적재 전후 품질 게이트가 위반 레코드를 격리하고 정상 데이터와 판정 결과를 함께 게시함
- 품질 이슈를 원천 시스템·변환 Job·소유자에 연결해 발생 원인과 조치 책임을 추적함
- 품질 점수만 평균하면 치명적 규칙이 가려지므로 규칙별 위반 수와 중요도를 함께 제시함

## Ⅲ. 종류 및 비교

| 판단 기준 | 완전성 | 정확성 | 일관성 |
|:---|:---|:---|:---|
| 핵심 질문 | 필요한 값과 레코드가 존재하는가 | 값이 신뢰 기준·업무 사실과 맞는가 | 같은 개체·규칙의 값이 서로 모순되지 않는가 |
| 대표 규칙 | 필수 열 Null·누락 구간·건수 대사 | 기준 코드·원천 대조·범위·주소 검증 | 시스템 간 키·상태·합계·참조 무결성 대사 |
| 실패 예 | 고객 ID 누락·이벤트 시간 구간 누락 | 잘못된 상품 가격·유효하지 않은 코드 | 주문 합계 불일치·고객 상태 상충 |
| 측정 지표 | 누락률·필수값 충족률 | 기준값 일치율·오류율 | 대사 차이·불일치율 |
| 주요 조치 | 수집 재처리·필수값 정책·격리 | 원천 수정·기준 데이터 적용·승인 | 공통 키·규칙 통일·변경 순서 조정 |

> 요약: 완전성은 누락, 정확성은 기준값 일치, 일관성은 시스템·시점 간 모순을 각각 규칙과 지표로 판정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Data Profile | 열 분포·Null·중복·범위·패턴을 계산해 기준선과 이상 후보를 제시함 |
| Rule Repository | 대상·차원·조건·임계값·중요도·소유자와 적용 버전을 관리함 |
| Validation Engine | 배치·스트림·DB에서 규칙을 실행하고 레코드별 판정 결과를 생성함 |
| Quality Gate·Quarantine | 임계값을 넘은 데이터의 게시를 제한하고 위반 레코드를 격리함 |
| Scorecard·Lineage | 규칙별 추이와 원천·변환·산출물의 품질 전파 경로를 보여줌 |
| Issue Workflow | 위반 원인을 소유자에게 배정하고 수정·예외·재검증 이력을 관리함 |

```text
원천 -> Profile·Rule -> Validation -> 정상 데이터
                               |
                         Quarantine·Issue
```

> 요약: 프로파일링과 규칙 실행 결과를 품질 게이트가 정상·격리 데이터로 나누고 이슈를 소유자에게 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
대상·목적 정의 -> 프로파일링 -> 규칙·임계값 설정 -> 실행·격리 -> 원인 조치·재검증
```

1. **대상 정의**: 중요 데이터 요소와 소비 목적·위험에 따라 품질 차원을 선택함
2. **현황 측정**: 분포·누락·중복·참조 관계를 프로파일링해 기준선을 계산함
3. **규칙 설정**: 판정 조건·허용 임계값·중요도·소유자·실패 처리를 등록함
4. **품질 판정**: 파이프라인에서 규칙을 실행하고 위반 데이터를 격리·기록함
5. **조치·재검증**: 원천·변환 원인을 수정한 뒤 같은 규칙으로 결과를 다시 측정함

> 요약: 데이터 품질은 목적별 규칙을 실행해 위반을 격리하고 원인을 수정한 뒤 같은 기준으로 재검증함.

## Ⅵ. 실무 사례

1. 주문 적재는 주문 ID 완전성과 금액 정확성을 검사하고 누락률·원천 대사 차이를 확인함
2. 고객 동기화는 시스템 간 상태 일관성을 검사하고 불일치율·미매핑 고객 수를 확인함

## Ⅶ. 결론

- 데이터 품질 관리는 사용 목적별 완전성·정확성·일관성 규칙과 임계값·소유자·재검증 절차로 운영해야 함
