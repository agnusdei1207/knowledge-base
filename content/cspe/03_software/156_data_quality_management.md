# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 품질 관리를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터가 업무 목적에 맞게 완전하고 정확하며 일관된지 규칙과 지표로 관리하는 활동
- **왜 필요한가**: 결측, 오입력, 중복, 코드 불일치가 누적되면 보고서 숫자, AI 학습 데이터, 운영 의사결정이 틀어진다.
- **핵심 직관**: 공장 품질검사처럼 데이터도 출하 전 불량률, 검사 기준, 책임자를 정해야 한다.

## 깊이 이해
- **배경·문제의식**: 데이터가 많아질수록 양보다 품질이 문제다. 완전성은 필수값이 채워졌는지, 정확성은 실제 세계와 맞는지, 일관성은 시스템 간 값과 정의가 같은지를 본다.
- **작동 원리**: 품질 규칙을 정의하고 파이프라인 실행 시 검사한다. 실패한 레코드는 격리하거나 재처리하고, owner에게 알림을 보내며, 결측률, 오류율, 중복률을 대시보드로 관리한다.
- **비유**: 식당 재료 검수와 같다. 재료가 빠졌는지, 유통기한이 맞는지, 주문서와 수량이 일치하는지 확인해야 요리가 가능하다.
- **구체 예시**: 주문 데이터에서 `order_id` null 0건, 주문금액 0원 미만 0건, ERP와 DW 일매출 차이 0.1% 이하를 품질 기준으로 둔다.
- **흔한 오해·주의점**: 품질 관리는 사후 정제가 아니다. 데이터 계약, CI 검사, 배치 차단, owner 알림까지 포함해야 재발을 줄일 수 있다.

## 연결 개념
- 데이터 계약 - producer와 consumer 간 품질 기준 합의
- ETL/ELT 파이프라인 - 품질 규칙 실행 지점
- 데이터 거버넌스 - 품질 owner와 개선 책임 지정

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 품질 답안은 완전성, 정확성, 일관성 정의와 함께 검사 위치, 차단 기준, owner 개선 프로세스를 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 품질 관리는 데이터의 완전성, 정확성, 일관성을 규칙, 검사, 알림, 개선 프로세스로 통제하는 체계임.
> 2. **가치**: 결측률, 오류율, 중복률, reconciliation gap을 수치로 관리해 보고와 AI 입력 오류를 줄임.
> 3. **판단 포인트**: 모든 오류를 차단하지 않고 위험 등급별로 reject, quarantine, warning 기준을 나누어야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 품질 차원 구분 확인 | 완전성, 정확성, 일관성 정의와 예시 | 품질을 막연한 신뢰로 표현 |
| 파이프라인 통제 확인 | rule, validation, quarantine, alert | 사후 정제만 서술 |
| 운영 지표 판단 확인 | null rate, error rate, duplicate rate | 수치 기준 누락 |

> 요약: 데이터 품질 문제는 차원별 규칙과 파이프라인 차단 기준을 함께 써야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터 품질 관리는 데이터 오류 통제 체계임.
- 배경: 결측, 오입력, 중복, 코드 불일치는 분석 결과와 업무 처리를 왜곡한다.
- 필요성: 완전성, 정확성, 일관성 규칙 기반 검증으로 데이터 사용 전 오류를 식별하고 개선 절차를 실행한다.

---

## Ⅱ. 구조 및 구성요소

```text
Data Source -> Quality Rule -> Validation Engine -> Quarantine/Load -> Alert/Dashboard
                              +-> Owner Remediation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 품질 규칙 | 필수값, 범위, 참조무결성, 중복 기준 정의 | Great Expectations, Deequ |
| 검증 엔진 | 배치/스트림 데이터 검사 | CI, Airflow, Spark 연계 |
| 격리 저장소 | 실패 레코드 보관과 재처리 | reject/quarantine 구분 |
| 알림/대시보드 | owner 통보와 품질 추세 관리 | SLA, SLO 기반 |

> 요약: 품질 관리는 규칙, 검증, 격리, 알림이 파이프라인에 내장되어야 작동함.

---

## Ⅲ. 동작원리 및 흐름도

```text
규칙 정의 -> 데이터 검사 -> 오류 분류 -> 차단/경고/격리 -> 원인 수정 -> 재검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 품질 차원과 규칙 정의 | 핵심 컬럼 rule coverage 95% |
| 2 | 적재 전/후 데이터 검사 | 검사 실행률 100% |
| 3 | 오류 심각도 분류 | P1/P2/P3 기준 |
| 4 | 차단, 격리, 경고 처리 | P1 데이터 적재 0건 |
| 5 | owner 수정과 재검증 | 재발률 5% 이하 |

> 요약: 품질 관리는 규칙 실행 후 오류를 등급별로 처리하고 재발률을 관리하는 반복 절차임.

## Ⅳ. 특징

| 구분 | 사후 정제 | 데이터 품질 관리 | 판단 포인트 |
|:---|:---|:---|:---|
| 시점 | 보고서 오류 발견 후 | 파이프라인 실행 중 | 적재 전 차단 |
| 기준 | 담당자 판단 | 규칙과 임계값 | null rate, error rate |
| 처리 | 수동 보정 | reject/quarantine/alert | P1 적재 0건 |
| 한계 | 구현 부담 낮음 | 규칙 유지 필요 | rule drift 관리 |

> 요약: 데이터 품질 관리는 사후 보정보다 규칙 기반 사전 검증과 책임 추적이 핵심임.

> 요약: 완전성, 정확성, 일관성을 별도 지표로 측정해야 품질 개선 방향을 특정할 수 있음.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 규칙 설정: 핵심 테이블 50개와 핵심 컬럼에 null, range, enum, referential rule을 정의하고 coverage 95% 이상 확보
2. 파이프라인 내장: Airflow/dbt/Spark 단계에 Great Expectations 또는 Deequ 검사를 넣고 P1 오류는 적재 차단
3. 개선 운영: 오류 레코드는 quarantine에 보관하고 owner 알림, RCA, 재검증을 통해 재발률 5% 이하 관리

**결론 (2줄):**
- 기술사 판단: 규제 보고, 결제, 고객 접점 데이터는 차단형 품질 검사를 적용하고 탐색 분석 데이터는 경고형으로 시작함
- 향후 방향: 데이터 계약과 observability가 결합되어 품질 오류를 배포 전 단계에서 차단하는 구조로 확장됨
