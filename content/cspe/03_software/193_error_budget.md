## 미리 알고가기

- 오류 예산은 SLO가 정한 기간에 허용하는 실패 비율 또는 실패 이벤트 수임
- SLO가 99.9%이면 같은 측정 기간의 오류 예산 비율은 0.1%임
- 좋은 이벤트는 SLI 기준을 충족한 요청이고 나쁜 이벤트는 기준을 벗어난 요청임
- 소진율은 허용 실패량 중 실제 실패가 사용한 비율임
- 번레이트는 관측 구간의 오류 예산 소진 속도를 SLO 기간의 허용 속도와 비교한 값임
- 오류 예산 정책은 잔여량·소진 속도에 따른 배포·복구·신뢰성 작업 조건을 정함

## 작성 근거(검토용)

- 오류 예산은 SLO 산출, 실패량, 소진율·번레이트, 배포 정책을 핵심 축으로 설명함
- 비교표는 정상 소진·소진 가속·예산 소진 상태에서 측정값과 운영 판단이 어떻게 달라지는지 대비함
- 절차는 SLI 측정부터 예산 계산·정책 판정·배포 또는 신뢰성 작업으로 이어지는 제어 순서를 따름

## Ⅰ. 개요

- **정의/개념**: 오류 예산은 SLO가 허용한 실패량을 계산하고 실제 실패의 소진율·번레이트로 변경 속도와 신뢰성 작업을 조정하는 운영 기준임
- **배경/필요성**: 무조건적인 무장애 목표 대신 사용자가 수용할 신뢰성 수준에서 배포 위험과 신뢰성 투자를 조정하기 위해 실패 허용량이 필요함

## Ⅱ. 특징

- 오류 예산 비율은 측정 기간의 SLO에 대해 $1-SLO$로 계산함
- 요청 기반 예산은 유효 이벤트 수와 허용 실패 비율을 곱해 실패 이벤트 수로 변환함
- 소진율은 이미 사용한 예산을, 번레이트는 예산이 소비되는 속도를 나타냄
- 예산 소진 상태는 배포 지속·배포 축소·변경 중단·신뢰성 작업 전환 조건으로 사용함

## Ⅲ. 종류 및 비교

| 판단 기준 | 정상 소진 | 소진 가속 | 예산 소진 |
|:---|:---|:---|:---|
| 예산 상태 | 잔여 예산이 정책 범위 유지 | 잔여 예산이 예상보다 이르게 감소 | 잔여 예산이 없거나 허용량 초과 |
| 경보 상태 | 번레이트가 정책 임계값 이내 | 단기·장기 번레이트 임계값 초과 | SLO 미달·초과 실패량 경보 발생 |
| 변경 판단 | 정책 범위에서 배포 진행 | 카나리 축소·롤백·원인 확인 | 예외 변경 외 배포 중단 |
| 작업 우선순위 | 기능과 신뢰성 작업 병행 | 사용자 영향 완화와 결함 수정 우선 | SLO 회복과 재발 완화 작업 우선 |
| 검증 지표 | 잔여 예산·SLO 준수율 | 다중 구간 번레이트·예상 소진 시간 | 초과 실패량·회복 기간 |

> 요약: 오류 예산 잔여량과 번레이트가 배포 지속·완화·중단과 신뢰성 작업 우선순위를 결정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SLI 이벤트 | 좋은 이벤트·유효 이벤트와 측정 위치를 정의함 |
| SLO·측정 기간 | 목표 비율과 예산을 계산할 시간 범위를 정함 |
| 예산 계산기 | 허용 실패량·실제 실패량·잔여 예산을 계산함 |
| 번레이트 경보 | 여러 관측 구간의 예산 소진 속도를 정책과 비교함 |
| 오류 예산 정책 | 상태별 배포·롤백·신뢰성 작업과 책임자를 정함 |
| 대시보드·보고서 | SLO 준수율·잔여 예산·주요 소진 사건을 공유함 |

```text
SLI 이벤트 -> SLO·기간 -> 오류 예산·번레이트 -> 정책 판정
                                              |-> 배포 지속·축소
                                              +-> 중단·신뢰성 작업
```

> 요약: SLI 실패량을 SLO 기간의 허용량과 비교해 오류 예산 상태와 변경 정책을 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
SLI 집계 -> 예산 산출 -> 소진율·번레이트 계산 -> 정책 판정 -> 변경·복구 실행 -> SLI 재측정
```

1. **SLI 집계**: 측정 기간의 좋은 이벤트와 유효 이벤트를 집계함
2. **예산 산출**: $1-SLO$와 유효 이벤트 수로 허용 실패량을 계산함
3. **소진 계산**: 실제 실패량을 반영해 잔여 예산과 여러 구간의 번레이트를 계산함
4. **정책 판정**: 예산 상태를 배포·롤백·중단 조건과 대조함
5. **조치·재측정**: 변경 또는 신뢰성 작업 후 SLI와 예산 회복 상태를 다시 확인함

> 요약: 실제 실패의 예산 소진 속도를 계산해 변경 정책을 집행하고 다시 측정함.

## Ⅵ. 실무 사례

1. API 배포는 오류 예산 번레이트로 카나리를 조정하고 잔여 예산·롤백 시간을 확인함
2. 데이터 파이프라인은 신선도 예산 소진 시 변경을 중단하고 지연 이벤트·회복 시간을 확인함

## Ⅶ. 결론

- 오류 예산은 사용자 SLI·SLO에서 계산하고 잔여량·번레이트를 배포와 신뢰성 작업 정책에 연결함
