# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 세마포어·뮤텍스·모니터는 여러 스레드가 **공유 자원에 동시에 접근하지 못하도록 상호 배제(Mutual Exclusion)를 보장**하는 세 가지 동기화 기법으로, 저수준 카운터(세마포어)→단일 소유 락(뮤텍스)→언어 차원 캡슐화(모니터) 순으로 추상화 수준이 높아진다.
- **왜 필요한가**: 두 스레드가 공유 변수를 동시에 읽고 쓰면 갱신이 덮어써지는 경쟁 상태(Race Condition)가 생긴다. 임계 구역(Critical Section)에 한 번에 하나만 들어가게 통제하는 동기화 도구가 없으면 데이터 무결성이 깨진다.
- **핵심 직관**: 화장실 열쇠를 생각하면 된다. 뮤텍스는 열쇠 1개를 쥔 사람만 들어가고 그 사람이 반드시 반납한다. 세마포어는 열쇠가 N개라 N명까지 동시 입장을 허용하는 개수 세기 도구다. 모니터는 아예 "문 여닫기와 열쇠 관리를 건물이 자동으로 해주는" 캡슐화된 방이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 답안용에 나오는 상호 배제 관련 표기·연산을 비유와 함께 먼저 세운다. 맨 위가 이 주제의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 상호 배제 (상위 키워드) | 임계 구역에 한 번에 하나의 스레드만 진입 | 한 칸 화장실은 한 명만 |
| 임계 구역 (Critical Section) | 공유 자원을 접근하는 보호 대상 코드 영역 | 열쇠가 필요한 화장실 내부 |
| 경쟁 상태 (Race Condition) | 동시 접근으로 결과가 실행 순서에 좌우됨 | 두 사람이 동시에 장부 고쳐 값이 꼬임 |
| 세마포어 (Semaphore) | 정수 카운터 기반 동기화, wait/signal 연산 | N개짜리 열쇠 꾸러미 |
| wait / P 연산 | 카운터를 1 감소, 0이면 대기 (자원 획득) | 열쇠 하나 집어감(없으면 기다림) |
| signal / V 연산 | 카운터를 1 증가, 대기자 깨움 (자원 반납) | 열쇠 다시 걸어둠 |
| 이진 세마포어 | 값이 0/1인 세마포어, 뮤텍스와 유사 | 열쇠 1개짜리 꾸러미 |
| 계수 세마포어 | 값이 N인 세마포어, N개 동시 접근 허용 | 열쇠 N개짜리 꾸러미 |
| 뮤텍스 (Mutex) | 소유권 있는 이진 락, 잠근 스레드만 해제 | 본인만 반납 가능한 열쇠 1개 |
| 소유권 (Ownership) | 락을 획득한 스레드만 해제 가능한 규칙 | 열쇠 가져간 사람이 반납 책임 |
| 모니터 (Monitor) | 공유 데이터+동기화를 캡슐화한 언어 구조 | 열쇠 관리를 자동화한 방 |
| 조건 변수 (Condition Variable) | 모니터 내 특정 조건 대기·통지 수단 (wait/signal) | "자리 나면 알려줘" 대기 벨 |
| 데드락 (Deadlock) | 락 획득 순서 엉킴으로 상호 대기 (009 참조) | 서로 열쇠 기다리며 정지 |

## 깊이 이해
- **배경·문제의식**: 초기 동기화는 세마포어(다익스트라, 1965)라는 정수 카운터와 wait/signal 두 연산만으로 이뤄졌다. 강력하지만 **개발자가 wait/signal을 직접 짝 맞춰 호출**해야 해, 순서를 바꾸거나 한쪽을 빠뜨리면 교착·경쟁 상태가 났다. 이 오류를 줄이려 소유권 개념을 넣은 뮤텍스, 나아가 락 관리를 언어가 대신 하는 모니터로 추상화가 발전했다.
- **작동 원리(어떻게+왜)**:
  - **세마포어**: 정수값 S와 대기 큐를 갖는다. wait(S)는 S를 1 줄이고 S<0이면 호출 스레드를 대기 큐로 보낸다. signal(S)는 S를 1 늘리고 대기자를 하나 깨운다. 값이 1이면 상호 배제(뮤텍스처럼), N이면 자원 N개 동시 사용 제어에 쓴다.
  - **뮤텍스**: 값이 0/1인 이진 락에 **소유권**을 더한 것이다. lock한 스레드만 unlock할 수 있어 "남이 함부로 signal하는" 세마포어의 오용을 막는다. 짧은 임계 구역 보호의 표준이다.
  - **모니터**: 공유 데이터와 그것을 다루는 프로시저를 하나로 묶고, **한 번에 하나의 스레드만 모니터 내부 프로시저를 실행**하도록 컴파일러/런타임이 자동 보장한다. 개발자는 lock/unlock을 직접 쓰지 않고, 특정 조건 대기는 조건 변수(wait/signal)로 처리한다. 자바 synchronized·wait/notify가 대표 구현이다.
- **비유**: 세마포어는 수동 신호기다 — 사람이 직접 깃발을 올리고 내려야 하고 실수하면 사고가 난다. 뮤텍스는 "가져간 사람만 반납"하는 규칙이 붙은 열쇠다. 모니터는 자동문이 달린 방으로, 들어가면 자동으로 잠기고 나오면 자동으로 풀려 사람이 열쇠를 만질 일이 없다.
- **구체 예시**: 자바에서 `synchronized void deposit()`는 모니터로, 메서드 진입 시 객체 락을 자동 획득하고 반환 시 자동 해제한다. 반면 POSIX `pthread_mutex_lock/unlock`은 뮤텍스로 개발자가 짝을 명시해야 하며, 세마포어 `sem_wait/sem_post`는 커넥션 풀에서 "동시 접속 10개 제한" 같은 계수 제어에 쓴다.
- **흔한 오해·주의점**: (1) **뮤텍스 = 이진 세마포어가 아니다.** 뮤텍스는 소유권이 있어 잠근 스레드만 풀 수 있지만, 이진 세마포어는 아무 스레드나 signal할 수 있다. (2) 모니터가 세마포어보다 항상 우월한 건 아니다 — 언어 지원이 필요하고 세밀한 제어(계수 제한)는 세마포어가 낫다. (3) 세마포어는 wait/signal 순서를 잘못 쓰면 교착·기아를 유발하며(009·011 참조), 이 오류 취약성이 모니터 등장의 핵심 동기다.

## 연결 개념
- 임계 구역과 상호 배제 조건(014 참조) — 세 기법이 공통으로 만족시켜야 할 진입 규칙
- 스핀락과 뮤텍스(013 참조) — 대기 방식(바쁜 대기 vs 블로킹)에 따른 락 구현 비교
- 교착상태(009 참조)·기아(011 참조) — 락 오용 시 발생하는 동기화 부작용

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 세마포어·뮤텍스·모니터는 임계 구역 상호 배제를 보장하는 동기화 기법으로, 카운터→소유권 락→언어 캡슐화 순으로 추상화가 높아짐.
> 2. **가치**: 추상화가 높아질수록 개발자의 락 관리 부담과 오용(순서 오류)이 줄어 경쟁 상태·교착 위험이 낮아짐.
> 3. **판단 포인트**: 계수 제어는 세마포어, 단일 자원 보호는 뮤텍스, 오류 안전성·복잡 조건 대기는 모니터가 적합함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세 기법의 원리 구분 | 세마포어(카운터)·뮤텍스(소유권)·모니터(캡슐화) | 뮤텍스와 이진 세마포어 동일시 |
| 상호 배제 보장 방식 | wait/signal·lock/unlock·자동 락 | 소유권 개념 누락 |
| 적합 상황 판단 | 계수 제어·단일 보호·오류 안전성 기준 | 모니터를 무조건 우월로 단정 |

> 요약: 세 기법을 추상화 수준으로 계열화하고, 소유권·계수 제어 여부로 적합 상황을 구분해 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 임계 구역에 한 번에 하나(또는 N개)의 스레드만 진입시키는 동기화 기법의 집합임
- 배경: 공유 자원 동시 접근 시 경쟁 상태로 데이터 무결성이 깨져 상호 배제 수단이 필요함
- 필요성: 세마포어의 수동 오용 위험을 소유권(뮤텍스)·캡슐화(모니터)로 줄여 동시성 오류를 예방함

## Ⅱ. 구조 및 구성요소

선형 구조도 (추상화 수준별 계열):

    세마포어(정수 S + 대기 큐) - wait/signal 수동 호출
      -> 뮤텍스(이진 락 + 소유권) - lock/unlock, 소유 스레드만 해제
      -> 모니터(공유데이터 + 프로시저 + 조건변수) - 진입 시 자동 락

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 세마포어 | 카운터로 자원 개수 제어 | wait/signal 개발자 직접 호출 |
| 뮤텍스 | 소유권 있는 이진 상호 배제 락 | 잠근 스레드만 해제 가능 |
| 모니터 | 데이터+동기화 캡슐화 구조 | 컴파일러·런타임이 락 자동 관리 |
| 조건 변수 | 모니터 내 조건 대기·통지 | wait로 대기·signal로 통지 |

> 요약: 세 기법은 카운터·소유권·캡슐화로 추상화 수준이 다르며, 위로 갈수록 락 관리를 시스템이 대신함.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도 (임계 구역 진입·해제):

    스레드 임계 구역 진입 시도
      -> [세마포어] wait(S): S-- , S<0이면 대기 큐 진입
      -> [뮤텍스] lock(): 소유권 획득, 점유 중이면 블로킹
      -> [모니터] 프로시저 호출 시 자동 락 획득
    임계 구역 실행 -> 종료 시 signal/unlock/자동 해제 -> 대기 스레드 진입

- 1단계 [진입 시도]: 스레드가 임계 구역 진입을 요청하면 각 기법이 상호 배제 조건을 검사함
- 2단계 [획득 또는 대기]: 세마포어는 카운터 감소, 뮤텍스는 소유권 획득, 모니터는 자동 락을 잡고, 불가하면 대기 큐로 보냄
- 3단계 [임계 구역 실행]: 획득에 성공한 하나의 스레드만 공유 자원을 접근함
- 4단계 [해제]: 종료 시 signal(세마포어)·unlock(뮤텍스)·자동 해제(모니터)로 대기 스레드 하나를 진입시킴

> 요약: 세 기법 모두 진입 시 배타적 권한을 획득하고 종료 시 반납하되, 반납을 수동/소유권/자동으로 처리하는 점이 다름.

## Ⅳ. 특징

- 추상화 계열성: 세마포어(저수준)→뮤텍스(소유권)→모니터(언어 캡슐화)로 관리 부담이 감소함
- 세마포어의 범용성: 계수 세마포어로 N개 동시 접근·생산자-소비자 등 유연한 제어가 가능함
- 뮤텍스의 안전성: 소유권으로 타 스레드의 임의 해제를 막아 세마포어보다 오용에 강함
- 모니터의 오류 내성: 락 획득·해제를 컴파일러가 보장해 짝 불일치 오류를 원천 차단함
- 공통 부작용: 셋 다 락 순서·중첩 오용 시 교착(009 참조)·기아(011 참조) 위험을 가짐

## Ⅴ. 심화 비교 및 적용 판단

세 동기화 기법을 소유권·계수 제어·오류 안전성 축으로 대조함(락 대기 방식 비교는 013 참조).

| 구분 | 세마포어 | 뮤텍스 | 모니터 |
|:---|:---|:---|:---|
| 상호 배제 방식 | 정수 카운터 wait/signal | 소유권 있는 이진 락 | 진입 시 자동 락 |
| 소유권 | 없음(누구나 signal) | 있음(잠근 스레드만 해제) | 있음(모니터가 관리) |
| 동시 접근 수 | N개(계수 세마포어) | 1개 | 1개 |
| 조건 대기 | 별도 세마포어로 구현 | 미지원(별도 조건변수 필요) | 조건 변수 내장 |
| 오류 취약성 | 높음(순서 수동 관리) | 중간(짝 명시 필요) | 낮음(언어가 자동 보장) |
| 대표 구현 | POSIX sem_wait/sem_post | pthread_mutex, std::mutex | Java synchronized, wait/notify |

> 요약: 자원 개수 제어는 세마포어, 단일 자원 보호는 뮤텍스, 복잡한 조건 대기·오류 안전성은 모니터가 적합함.

**리스크·대응:**
- 세마포어 오용 — wait/signal 짝 불일치로 교착·기아 발생 — 뮤텍스·모니터로 대체해 소유권·자동 관리 적용
- 데드락 — 다중 락 획득 순서 엉킴 — 전역 락 순서 강제·tryLock 타임아웃 도입(009 참조)
- 우선순위 역전 — 저순위 락 점유로 고순위 대기 — 우선순위 상속 프로토콜 적용(011 참조)

**점검 지표:**
- 성능: 락 획득 대기 시간(p99), 임계 구역 평균 점유 시간
- 운영: 락 경합(contention) 비율, 교착 발생 건수

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 자원 풀 계수 제어: DB 커넥션·동시 다운로드 상한처럼 N개 동시 사용 제한에 계수 세마포어(sem_wait/sem_post) 적용
2. 짧은 임계 구역 보호: 공유 변수·자료구조 단일 접근에 뮤텍스(std::mutex, pthread_mutex)로 소유권 기반 배제 적용
3. 복합 조건 동기화: 생산자-소비자·버퍼 조건 대기에 모니터(Java synchronized+wait/notify)로 조건 변수와 자동 락을 함께 활용

**결론:**
- 기술사 판단: 계수 제어가 필요하면 세마포어, 단순 상호 배제는 뮤텍스, 오류 안전성·조건 대기가 중요하면 모니터를 선택함
- 향후 방향: 락 경합 비용을 줄이기 위해 무잠금(lock-free)·CAS 기반 원자 연산과 언어 내장 동시성(고루틴 채널·액터 모델)으로 추상화가 확산됨

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "세마포어·뮤텍스·모니터를 설명하시오" | 세 기법의 구조·진입 해제 흐름 | 추상화 계열·적합 상황 판단 |

> 요약: 포괄형은 세 기법의 원리와 흐름을, 비교형은 소유권·계수 제어 차이와 선택 기준을 답안 무게중심으로 둠.
