## Ⅰ. 개요
- 시스템 내부 구성 요소들이 시간에 따라 상호작용하는 동적인 흐름을 표현함.
- 시퀀스(Sequence)는 메시지 교환을, 상태(State)는 객체의 생명주기를 나타냄.
- 출제 의도: 시나리오에 따른 메시지 흐름 및 상태 전이 조건 설계 역량 확인.

## Ⅱ. 구성요소
- 시퀀스 및 상태 요소
[Lifeline] --- (Message) ---> [Target] | [State A] -- (Event) --> [State B]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Lifeline | 객체의 존재 기간을 나타내는 수직 점선 | 사람의 인생선 |
| Message | 객체 간 상호작용을 위해 주고받는 신호 | 대화/요청 |
| Transition | 특정 이벤트 발생 시 상태가 변하는 경로 | 신호등 변경 |
> 요약: 시간 순서와 이벤트 기반의 동적 동작 방식을 정의함.

## Ⅲ. 절차
- 행위 모델링 과정
[Scenario Selection] -> [Object Ident] -> [Flow Design] -> [Logic Check]

1. 시나리오 선정: 유스케이스 중 중요도가 높은 비즈니스 흐름을 선택함.
2. 참여 객체 도출: 상호작용에 참여하는 주요 라이프라인을 배치함.
3. 메시지 설계: 객체 간 호출 순서와 응답 흐름을 수평 화살표로 표현함.
4. 제어 로직 추가: 루프(Loop), 조건문(Alt) 등을 활용하여 흐름을 완성함.
> 요약: 기능이 수행되는 절차와 조건을 시각화하여 로직의 완결성 확보함.

## Ⅳ. 문제점
- 복잡한 분기 로직 표현의 한계 및 전체 시스템 흐름 파악의 어려움.

## Ⅴ. 개선방안
- 복잡한 로직은 서브 다이어그램으로 분리하고 시각적 가독성 최우선 고려.

## Ⅵ. 전망
- 실시간 실시간 분산 시스템의 트레이싱 로그와 결합된 동적 시각화 기술 발전.
- 상태 머신 모델링을 통한 임베디드 및 IoT 제어 로직의 자동 코드 생성 강화.
