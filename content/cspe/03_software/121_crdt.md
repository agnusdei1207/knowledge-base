## 미리 알고가기

- CRDT는 여러 복제본이 따로 바뀌어도 같은 결과로 합쳐지게 만든 자료구조임
- 연산 순서가 달라져도 결과가 같아야 병합이 쉬움
- 협업 편집과 오프라인 동기화처럼 동시에 수정이 많이 일어나는 환경에서 자주 씀

## Ⅰ. 개요

- **정의/개념**: CRDT는 네트워크가 끊기거나 여러 사용자가 동시에 수정해도 각 복제본이 독립적으로 갱신된 뒤 같은 규칙으로 병합돼 결국 동일한 상태로 수렴하도록 만든 분산 자료구조임
- **배경/필요성**: 실시간 협업과 모바일 오프라인 환경에서는 모든 변경을 중앙에서 순서대로 처리하기 어렵기 때문에 로컬 수정과 자동 병합을 함께 만족시키는 구조가 필요함

## Ⅱ. 특징

- 중앙 잠금 없이도 각 복제본이 바로 수정될 수 있음
- 병합 규칙만 맞으면 별도 충돌 조정 절차 없이도 수렴이 가능함
- 단순히 마지막 값만 남기는 방식보다 의미를 더 잘 보존할 수 있음
- 메타데이터가 커지거나 업무 규칙과 맞지 않으면 오히려 복잡해질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 상태 기반 CRDT | 연산 기반 CRDT |
|:---|:---|:---|
| 전파 대상 | 현재 상태 전체나 일부 | 수행한 연산 |
| 장점 | 이해와 구현이 비교적 쉬움 | 전송량을 줄이기 좋음 |
| 주의점 | 상태가 크면 부담이 커짐 | 연산 전달 순서와 중복 처리가 중요함 |
| 잘 맞는 환경 | 단순 동기화, 작은 객체 | 상호작용이 잦은 협업 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 로컬 상태 | 각 복제본이 자기 데이터를 따로 유지함 |
| 병합 규칙 | 여러 변경을 같은 결과로 합치는 기준임 |
| 전파 채널 | 상태나 연산을 다른 복제본으로 보냄 |
| 메타데이터 | 중복 적용과 병합 순서를 판단하는 단서를 담음 |

```text
+---------+      +---------+      +---------+
| 복제본 A | ---> | 병합 규칙 | <--- | 복제본 B |
+---------+      +---------+      +---------+
      \                                 /
       \---------> 같은 상태로 수렴 <------/
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 각자 로컬 수정   | --> | 변경 내용 전파   | --> | 병합 규칙 적용  | --> | 같은 상태로 수렴 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **각자 로컬 수정**: 사용자는 네트워크 상태와 무관하게 변경을 수행함
2. **변경 내용 전파**: 상태나 연산을 다른 복제본으로 보냄
3. **병합 규칙 적용**: 서로 다른 변경을 하나의 결과로 합침
4. **같은 상태로 수렴**: 모든 복제본이 같은 값에 도달함

## Ⅵ. 실무 적용 및 유의점

1. 공동 편집이나 오프라인 메모처럼 동시에 수정이 많은 데이터는 CRDT가 잘 맞지만 메타데이터가 빠르게 불어날 수 있으므로 동기화 전송량과 병합 지연 시간으로 운영 부담을 계속 확인함
2. 주문 상태처럼 순서와 승인 규칙이 중요한 업무는 CRDT만으로 의미를 보장하기 어렵기 때문에 적용 전 병합 뒤 값의 정확도와 수동 정정 건수로 자료구조 적합성을 먼저 검증함

## Ⅶ. 결론

CRDT의 핵심은 충돌을 마법처럼 없애는 데 있지 않고 여러 복제본의 변경을 어떤 규칙으로 같은 결과에 모을지 자료구조 수준에서 미리 정하는 데 있음.
