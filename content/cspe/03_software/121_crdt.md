## 미리 알고가기

- CRDT는 여러 복제본을 중앙 잠금 없이 갱신하고 결정적 규칙으로 수렴시키는 분산 자료구조임
- 상태 기반 CRDT는 상태 병합 함수의 교환·결합·멱등 성질로 중복·순서 변경을 허용함
- 연산 기반 CRDT는 동시 연산의 교환 성질과 신뢰성 있는 전달 조건으로 수렴함
- 인과 메타데이터는 버전 벡터·논리 시계처럼 변경의 선후 관계와 중복 적용 여부를 나타냄

## 작성 근거(검토용)

- CRDT는 전파 단위, 수렴 조건, 전달 조건, 메타데이터 비용을 핵심 판단축으로 설명함
- 상태 기반과 연산 기반의 수렴 전제가 다르므로 비교표와 절차에서 각각의 조건을 구분함
- 실무 사례는 협업 문서와 오프라인 동기화에서 수렴 시간·메타데이터·전송량으로 검증함

## Ⅰ. 개요

- **정의/개념**: CRDT는 여러 복제본의 동시 변경을 자료형별 병합 규칙으로 결합해 중앙 잠금 없이 같은 상태로 수렴시키는 분산 자료구조임
- **배경/필요성**: 협업 편집과 오프라인 애플리케이션에서 네트워크 단절 중에도 변경을 허용하기 위해 로컬 갱신과 결정적 병합 구조가 필요함

## Ⅱ. 특징

- 각 복제본이 중앙 잠금 없이 갱신을 수락해 네트워크 단절 중에도 쓰기 가용성을 유지함
- 상태 병합 또는 연산 적용 규칙이 수학적 수렴 조건을 충족하면 전파 순서가 달라도 같은 결과에 도달함
- 카운터·집합·시퀀스처럼 자료형별 동시 변경 의미를 병합 규칙에 명시함
- 버전 벡터·삭제 표식이 누적될 수 있고 승인 순서·재고 하한 같은 업무 불변식은 별도 조정이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 상태 기반 CRDT | 연산 기반 CRDT |
|:---|:---|:---|
| 전파 단위 | 전체 상태 또는 변경된 상태 델타 | 로컬에서 생성한 변경 연산 |
| 수렴 조건 | 병합 함수가 교환·결합·멱등 성질을 충족 | 동시 연산이 교환 가능하고 같은 연산을 중복 적용하지 않음 |
| 전달 조건 | 순서 변경·중복을 허용하되 모든 상태가 최종 전달돼야 함 | 신뢰성 있는 전달과 자료형에 따른 인과 순서가 필요함 |
| 통신 비용 | 상태 크기에 따라 전송량이 증가함 | 연산 크기만 전송해 메시지당 전송량이 작음 |
| 상태 비용 | 버전 벡터·삭제 표식과 상태 델타를 관리함 | 연산 식별자·전달 확인·인과 메타데이터를 관리함 |
| 적합 조건 | 상태 크기가 제한되고 비정기 동기화가 필요한 복제본 | 변경 빈도가 높고 전달 계층을 통제할 수 있는 협업 서비스 |

> 요약: 상태 기반은 멱등 병합으로 중복·순서 변경을 허용하고, 연산 기반은 교환 가능한 연산과 신뢰성 있는 전달로 수렴함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 복제본 상태 | 각 노드가 로컬 읽기·쓰기에 사용하는 CRDT 값을 유지함 |
| 상태 델타·변경 연산 | 다른 복제본에 전파할 상태 차이 또는 갱신 명령을 표현함 |
| 인과 메타데이터 | 버전 벡터·논리 시계·연산 식별자로 선후 관계와 중복을 판정함 |
| 병합·적용 함수 | 상태를 결합하거나 연산을 적용해 자료형별 수렴 규칙을 실행함 |
| 전파 계층 | 안티엔트로피나 메시지 브로커로 상태·연산을 최종 전달함 |

```text
+---------+      +---------+      +---------+
| 복제본 A | ---> | 병합·적용 | <--- | 복제본 B |
+---------+      +---------+      +---------+
      \                                 /
       \----------> 동일 상태 수렴 <-------/
```

> 요약: 복제본은 상태 델타나 변경 연산을 교환하고 인과 메타데이터와 병합·적용 함수로 같은 상태에 수렴함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 로컬 변경 수락   | --> | 상태·연산 생성   | --> | 복제본 전파    | --> | 병합·적용/수렴 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **로컬 변경 수락**: 각 복제본이 현재 상태에 사용자 변경을 반영함
2. **전파 단위 생성**: 상태 기반은 상태·델타를, 연산 기반은 고유 식별자를 포함한 연산을 생성함
3. **복제본 전파**: 안티엔트로피 또는 메시지 계층이 변경 내용을 다른 복제본에 전달함
4. **병합·적용**: 상태 기반은 멱등 병합하고 연산 기반은 중복을 제거한 뒤 연산을 적용함
5. **수렴 확인**: 전파가 끝난 복제본의 상태 해시와 업무 불변식을 확인함

> 요약: 상태 기반은 상태를 멱등 병합하고 연산 기반은 중복 제거 후 연산을 적용해 복제본을 수렴시킴.

## Ⅵ. 실무 사례

1. 공동 편집 서비스는 시퀀스 CRDT의 인과 메타데이터를 압축하고 문서당 메타데이터 크기·재동기화 시간을 확인함
2. 오프라인 현장 앱은 상태 델타와 안티엔트로피를 적용하고 수렴 시간·동기화 전송량을 확인함

## Ⅶ. 결론

- CRDT는 상태 크기·변경 빈도·전달 보장 조건과 업무 불변식을 기준으로 상태 기반·연산 기반 적용 여부를 선택해야 함
