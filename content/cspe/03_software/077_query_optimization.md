## Ⅰ. 개요
- SQL 질의를 가장 효율적으로 실행하기 위해 최적의 경로를 결정하는 DBMS의 핵심 기능임.
- 옵티마이저(Optimizer)가 통계 정보를 바탕으로 실행 계획(Execution Plan)을 수립함.
- 출제 의도: 규칙 기반(RBO)과 비용 기반(CBO) 옵티마이저 차이 및 튜닝 원리 이해.

## Ⅱ. 구성요소
- 옵티마이저 유형
[SQL] -> [Optimizer (RBO/CBO)] -> [Execution Plan]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| RBO | 정해진 우선순위 규칙에 따라 경로 결정 | 매뉴얼대로 행동 |
| CBO | 데이터 통계(카디널리티 등)로 예상 비용 계산 | 실시간 교통정보 반영 |
| Hint | 개발자가 명시적으로 최적화 경로 지정 | 내비게이션 경유지 설정 |
> 요약: 통계 데이터와 알고리즘을 결합하여 최적의 접근 전략을 수립함.

## Ⅲ. 절차
- 쿼리 최적화 단계
[Parsing] -> [Query Transformation] -> [Estimation] -> [Plan Selection]

1. 구문 분석: SQL의 문법과 유효성을 검사하고 파싱 트리 생성함.
2. 질의 변환: 논리적으로 동일한 더 효율적인 형태로 쿼리 재작성함.
3. 비용 산정: I/O, CPU 사용량 등 하드웨어 자원 소모량 예측함.
4. 계획 확정: 산정된 비용이 가장 낮은 실행 계획을 최종 선택함.
> 요약: 논리적 변환과 물리적 비용 평가를 거쳐 최적의 실행 지침을 만듦.

## Ⅳ. 문제점
- 부정확한 통계 정보로 인한 잘못된 실행 계획 수립 및 성능 급락(Regression).

## Ⅴ. 개선방안
- 주기적인 통계 업데이트(Analyze) 및 SQL Plan Baseline을 통한 성능 고정.

## Ⅵ. 전망
- 머신러닝 기반 자가 학습 옵티마이저가 쿼리 패턴을 분석하여 실시간 튜닝 지원.
- 클라우드 환경의 자원 가용성에 따른 동적 실행 계획 변경 기술 고도화.
