## Ⅰ. 개요
- 정의: 프로그램을 실행하지 않고 소스 코드 수준에서 결함 및 보안 취약점을 분석하는 도구
- 배경: 실행 테스트 전에 코딩 규칙 위반·결함 패턴·취약한 데이터 흐름을 식별할 필요
- 출제 의도: 정적 분석의 메커니즘 및 SonarQube의 주요 기능 이해 측정

## Ⅱ. 구성요소
- 구조도
  [Git] -> [CI (Jenkins)] -> [Sonar Scanner] -> [SonarQube Server]
                                                    |-- Database
                                                    |-- Dashboard

- 구성요소 표
| 분석 항목 | 설명 | 비유 |
| :--- | :--- | :--- |
| Code Smells | 유지보수를 어렵게 만드는 잠재적 문제 | 불쾌한 냄새(징후) |
| Bugs | 런타임 오류를 유발할 수 있는 명백한 결함 | 지뢰 |
| Vulnerabilities | 해킹 공격의 통로가 될 수 있는 보안 약점 | 열린 문 |
> 요약: 규칙과 데이터 흐름 분석으로 버그·취약점·코드 스멜을 분류하고 위치를 제시함

## Ⅲ. 절차
- 흐름도
  Rule-set 설정 -> 스캔 수행 -> 결과 분석 -> 이슈 할당 및 조치
- 4단계 설명
1. Rule-set 설정: 언어별 표준 코딩 규칙 및 보안 정책 정의
2. 스캔 수행: 소스 코드를 구문 분석하여 패턴 매칭 및 데이터 흐름 추적
3. 결과 분석: 품질 게이트(Quality Gate) 통과 여부 확인 및 기술 부채 산출
4. 이슈 할당: 발견된 이슈를 담당 개발자에게 할당하고 리팩토링 수행
> 요약: 스캔 결과를 품질 게이트 기준과 비교하고 담당자 조치 후 재분석함

## Ⅳ. 문제점
- 과도한 오탐(False Positive) 발생 시 개발자의 도구 신뢰도 저하 및 피로도 증가
- 분석 시간이 길어질 경우 CI/CD 파이프라인의 전체 병목 현상 유발

## Ⅴ. 개선방안
- 프로젝트 성격에 맞는 점진적 Rule-set 최적화 및 예외 처리 가이드 수립
- 증분 분석(Incremental Analysis) 기법 도입으로 분석 시간 단축 및 효율화

## Ⅵ. 전망
- LLM 기반의 AI 코드 리뷰 기능과 결합하여 수정 가이드 자동 생성 기능 강화
- CSF: 'Shift Left' 전략의 핵심 도구로서 개발자 IDE 단계부터 분석 연동 강화
