## 미리 알고가기

- 도메인 소유권은 데이터 생성 맥락을 아는 업무 팀이 분석 데이터의 품질과 수명주기를 책임지는 원칙임
- 데이터 제품은 명확한 소유자·사용 목적·접근 인터페이스·품질 지표를 갖춘 독립 제공 단위임
- 셀프서비스 데이터 플랫폼은 도메인 팀에 저장·처리·배포·관찰 기능을 표준 인터페이스로 제공함
- 연합 거버넌스는 전사 공통 정책과 도메인별 실행 책임을 분리하고 자동 검증으로 연결함
- 상호운용성은 여러 데이터 제품이 공통 식별자·스키마·정책으로 조합될 수 있는 성질임
- 데이터 계약은 생산자와 소비자가 스키마·의미·품질·변경 호환성에 합의한 규약임

## 작성 근거(검토용)

- 데이터 메시는 도메인 소유권·데이터 제품·셀프서비스 플랫폼·연합 거버넌스의 네 원칙을 핵심으로 선정함
- 비교표는 중앙 데이터 플랫폼과 소유권·제공 단위·변경 대응·플랫폼·거버넌스·적합 조직을 대비함
- 순차 동작보다 책임과 구조가 핵심이므로 별도 Ⅴ절을 두지 않고 구성요소 관계를 중심으로 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 조직 원칙과 기술 구성의 범위를 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 메시는 도메인이 데이터 제품을 소유하고 셀프서비스 플랫폼·연합 거버넌스로 품질과 상호운용성을 관리하는 원칙임
- **배경/필요성**: 중앙 데이터 팀의 업무 맥락 부족과 변경 대기열을 줄이면서 도메인 간 데이터 조합을 유지하기 위해 소유권과 공통 정책의 분리가 필요함

## Ⅱ. 특징

- 도메인 팀이 운영 데이터와 함께 분석 데이터 제품의 코드·데이터·메타데이터를 소유함
- 데이터 제품은 검색 메타데이터·접근 인터페이스·품질 지표·보안 정책을 소비자에게 제공함
- 셀프서비스 플랫폼이 파이프라인·저장·카탈로그·관찰·정책 적용의 공통 기능을 제공함
- 연합 거버넌스가 전사 상호운용 규칙을 정하고 도메인이 제품 단위로 정책을 실행함
- 도메인 경계와 공통 식별자 없이 분산하면 중복 제품과 의미 불일치가 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 중앙 데이터 플랫폼 | 데이터 메시 |
|:---|:---|:---|
| 데이터 소유권 | 중앙 데이터 팀이 수집·가공·제공 | 도메인 팀이 데이터 제품 수명주기 소유 |
| 제공 단위 | 공용 웨어하우스·레이크의 테이블 | 목적·인터페이스·SLO를 갖춘 데이터 제품 |
| 변경 대응 | 도메인 요청을 중앙 작업 대기열로 처리 | 도메인이 원천 변화와 제품을 함께 변경 |
| 플랫폼 역할 | 중앙 팀이 파이프라인까지 직접 구현 | 셀프서비스 기능으로 도메인 구현 지원 |
| 거버넌스 | 중앙 승인과 표준 적용 | 공통 정책과 도메인 실행의 연합 구조 |
| 적합 조직 | 도메인·데이터 원천 수가 제한된 조직 | 다수 도메인과 소비 사례가 독립 변화하는 조직 |

> 요약: 데이터 메시는 도메인에 데이터 제품 소유권을 두고 플랫폼·연합 거버넌스로 제품 간 품질과 상호운용성을 유지함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Domain Team | 원천 맥락과 소비 요구를 반영해 데이터 제품을 개발·운영함 |
| Data Product | 코드·데이터·메타데이터·인터페이스·SLO를 하나의 제공 단위로 묶음 |
| Product Owner | 소비자·품질·우선순위·수명주기와 변경 호환성을 책임짐 |
| Self-Service Platform | 저장·처리·배포·카탈로그·관찰·정책 도구를 공통 제공함 |
| Federated Governance | 전사 식별자·스키마·보안·품질 규칙과 도메인 실행 책임을 정함 |
| Catalog·Product Graph | 제품 검색·계보·계약·소유권과 제품 간 의존성을 연결함 |

```text
도메인 A 제품 ----+
도메인 B 제품 ----+-> Self-Service Platform -> 소비자
도메인 C 제품 ----+          |
                    Federated Governance
```

> 요약: 도메인 제품은 셀프서비스 플랫폼에서 독립 운영되고 연합 거버넌스가 공통 정책과 조합 기준을 적용함.

## Ⅵ. 실무 사례

1. 주문 도메인은 주문 이력 제품에 계약·소유자를 지정하고 최신성 SLO·품질 규칙 통과율을 확인함
2. 장애 분석 제품은 공통 서비스 ID를 적용하고 미매핑 이벤트 수·계보 연결률을 확인함

## Ⅶ. 결론

- 데이터 메시는 도메인 자율성·제품 책임·셀프서비스 기능과 공통 정책의 플랫폼 검증 가능성을 기준으로 도입해야 함
