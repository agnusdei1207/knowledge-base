## Ⅰ. 개요
- **정의**: 외부 동작을 변경하지 않고 내부 구조를 개선하는 코드 변환 기법임
- **배경/필요성**: 기능 추가가 반복되면 코드 복잡도가 증가하므로 구조적 정리를 통해 변경 용이성을 확보해야 함
- **비유**: 방 안 가구 배치를 바꿔 동선을 개선하되 방 용도는 그대로 유지하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 리팩터링 기법과 적용 시점 | 코드 스멜 유형별 대응 기법 매핑 | 기능 변경과 혼동하지 말 것 |

> 요약: 동작 보존 하에 내부 구조를 개선하여 유지보수성을 높이는 기법임

## Ⅱ. 구성요소
```text
[리팩터링 구조]
  코드 스멜(Code Smell) ---> 리팩터링 촉발 신호
        |
        v
  리팩터링 기법(Technique) -> 구조 변환 규칙
        |
        v
  테스트 스위트(Test Suite) -> 동작 보존 검증 수단
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 코드 스멜 | 중복, 긴 메서드, 과대 클래스 등 구조 열화 징후임 | 이상 냄새 감지 |
| 리팩터링 기법 | Extract Method, Move Field 등 구조 변환 패턴임 | 수술 기법 목록 |
| 테스트 스위트 | 변환 전후 동작 동일성을 자동 검증하는 테스트 집합임 | 수술 후 검진 |

> 요약: 스멜 감지-기법 적용-테스트 검증 3요소로 구성됨

## Ⅲ. 절차
```text
스멜 감지 --> 테스트 확보 --> 기법 적용 --> 회귀 검증
```
- 1단계: 스멜 감지 — 정적 분석 또는 코드 리뷰로 구조 열화 지점을 식별함
- 2단계: 테스트 확보 — 대상 코드의 현재 동작을 커버하는 테스트를 마련함
- 3단계: 기법 적용 — 소규모 단위로 구조 변환을 수행함(한 번에 하나의 기법)
- 4단계: 회귀 검증 — 테스트 스위트를 실행하여 동작 보존을 확인함

> 요약: 감지-테스트-적용-검증의 소규모 반복 순환으로 안전하게 구조를 개선함

## Ⅳ. 문제점
- 테스트 부재: 레거시 코드에 테스트가 없으면 동작 보존 검증이 불가함 — 변환 리스크 증가
- 범위 확산: 한 지점 수정이 연쇄 변경을 유발함 — 작업량 예측 곤란
- 성과 비가시: 외부 동작이 동일하므로 경영층에 가치를 설명하기 어려움 — 투자 승인 지연

> 요약: 테스트 부재, 범위 확산, 성과 비가시가 리팩터링 적용의 장벽임

## Ⅴ. 개선방안
1. 단기: 특성화 테스트(Characterization Test)를 우선 작성하여 레거시 동작을 포착함
2. 중기: 변경 영향 분석 도구를 도입하여 연쇄 변경 범위를 사전 파악함
3. 장기: 기술 부채 이자 절감액(091 참조)을 정량 제시하여 투자 타당성을 확보함

> 요약: 테스트 확보-영향 분석-가치 정량화 순서로 리팩터링 장벽을 해소함

## Ⅵ. 전망
- 발전 방향: AI 보조 리팩터링 도구가 스멜 탐지와 기법 제안을 자동화하는 추세임
- 기술사적 판단: 리팩터링은 기술 부채 상환의 핵심 수단으로 개발 프로세스에 내재화해야 함
- 기술사 제언: CI 파이프라인에 코드 품질 게이트를 설정하여 리팩터링을 일상화할 필요
