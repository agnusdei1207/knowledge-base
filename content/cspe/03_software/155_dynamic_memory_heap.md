## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 프로그램 실행 중 필요한 크기만큼 메모리를 요청하고 해제하는 기법 |
| 필요성 | 실행 전 데이터 크기 미확정 상황 대응 및 가변적 자료구조(트리, 리스트) 구현 |
| 출제 의도 | 힙(Heap) 관리 방식, 단편화 해결 알고리즘, 메모리 누수 방지 역량 |

## Ⅱ. 구성요소
```text
[ Memory Layout ]           [ Heap Manager ]
+-------------+ high        - Binning: 크기별 리스트 관리
|    Stack    |             - Coalescing: 빈 공간 합치기
+-------------+             - Splitting: 공간 쪼개기
|      v      |
|    Heap     |             [ Common APIs ]
+-------------+ low         - malloc() / free()
|    Data     |             - new / delete
+-------------+             - GC (Garbage Collection)
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 힙 (Heap) | 동적 할당을 위해 비어 있는 거대 메모리 풀 | 공용 주차장 |
| 프리 리스트 | 할당 가능한 빈 블록들의 주소를 관리하는 목록 | 주차 가능 구역도 |
| 헤더 (Header) | 할당된 블록 앞에 붙어 크기 등 메타데이터 저장 | 주차권 정보 |
> 요약: 스택은 정적/자동 관리되지만, 힙은 개발자 또는 런타임이 명시적으로 관리함.

## Ⅲ. 절차
```text
Request Size -> Search Free List -> Split Block -> Update Meta -> Return Addr
      ^                                                     |
      +----- (Not Found) ----- Request OS (sbrk/mmap) <-----+
```
1. 할당 요청: 프로그램이 런타임 라이브러리에 특정 바이트 수만큼 메모리 요청.
2. 적합 블록 탐색: First-fit, Best-fit 등 정책에 따라 프리 리스트에서 탐색.
3. 분할 및 할당: 큰 블록을 발견하면 필요한 만큼 쪼개고 나머지는 다시 리스트에 유지.
4. 해제 및 통합: free() 호출 시 해당 블록을 빈 리스트에 넣고 인접 빈 블록과 합침.
> 요약: 효율적인 탐색과 단편화 억제가 힙 관리의 핵심 성능 지표임.

## Ⅳ. 문제점
- 할당 후 해제 누락 시 발생하는 메모리 누수(Memory Leak)로 인한 시스템 고갈.
- 할당/해제 반복 시 작은 빈 공간만 남는 외부 단편화로 대형 객체 할당 실패.

## Ⅴ. 개선방안
- 가비지 컬렉터(GC)를 도입하여 사용되지 않는 객체를 자동으로 감지 및 회수.
- 스마트 포인터(RAII 패턴)를 사용하여 객체 소멸 시 메모리가 자동 해제되도록 설계.

## Ⅵ. 전망
- 지능형 할당기: 머신러닝을 통해 앱의 할당 패턴을 학습하여 최적의 블록 크기 미리 준비.
- 하드웨어 힙 보호: 태그된 메모리(MTE) 기술로 잘못된 힙 접근(UAF 등) 실시간 차단.
