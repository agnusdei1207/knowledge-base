## 미리 알고가기

- eBPF는 검증된 프로그램을 커널 훅에서 이벤트에 따라 실행하는 Linux 실행 기술임
- kprobe·tracepoint·소켓·XDP·TC는 커널 함수와 네트워크 경로의 eBPF 부착 지점임
- eBPF 맵은 커널 프로그램의 상태 저장과 사용자 공간 통신에 사용함
- 링 버퍼는 eBPF 이벤트를 커널에서 사용자 공간 수집기로 순서대로 전달함
- 검증기는 레지스터·메모리·제어 흐름을 분석해 안전 조건을 충족한 프로그램만 적재함

## 작성 근거(검토용)

- eBPF 네트워크 관측은 커널 훅, 검증기, 맵·링 버퍼, 사용자 공간 수집기를 핵심 축으로 설명함
- 비교표는 패킷 캡처와 수집 위치·실행 문맥·수집 단위·운영 제약을 같은 수준에서 대비함
- 절차는 프로그램 적재·검증·부착 후 네트워크 이벤트가 사용자 공간으로 전달되는 순서를 따름

## Ⅰ. 개요

- **정의/개념**: eBPF 네트워크 관측은 검증된 프로그램을 커널 네트워크 훅에 부착하고 흐름·지연·드롭 이벤트를 맵과 링 버퍼로 수집하는 방식임
- **배경/필요성**: 컨테이너·프로세스별 네트워크 동작을 애플리케이션 수정 없이 연결 문맥과 함께 분석하기 위해 커널 관측 지점이 필요함

## Ⅱ. 특징

- 패킷·소켓·시스템 호출이 지나는 커널 훅에서 이벤트를 선택해 수집함
- PID·cgroup·네임스페이스·소켓 정보와 네트워크 흐름을 같은 문맥으로 연결함
- 검증기가 안전 조건을 확인하고 승인된 프로그램만 커널 훅에서 실행함
- 맵은 집계 상태를 보존하고 링 버퍼는 이벤트를 사용자 공간 수집기로 전달함

## Ⅲ. 종류 및 비교

| 판단 기준 | eBPF 관측 | 패킷 캡처 |
|:---|:---|:---|
| 수집 위치 | 커널 함수·소켓·XDP·TC 훅 | 네트워크 인터페이스의 패킷 경로 |
| 실행 문맥 | 프로세스·cgroup·네임스페이스와 연결 | 주소·포트·프로토콜 중심으로 식별 |
| 수집 단위 | 선택 이벤트·집계값·스택 정보 | 패킷 헤더와 선택한 페이로드 |
| 데이터 전달 | 맵·링 버퍼로 사용자 공간에 전달 | 캡처 버퍼와 파일·수집기로 전달 |
| 운영 제약 | 커널 기능·검증기·프로그램 권한 확인 | 캡처 범위·저장량·암호화 구간 확인 |
| 적합 조건 | 워크로드 문맥과 커널 경로 분석 | 패킷 내용과 프로토콜 교환 분석 |

> 요약: eBPF는 커널 훅의 네트워크 이벤트를 프로세스·cgroup 문맥과 연결해 수집함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 로더 | eBPF 객체를 커널에 적재하고 맵·부착 지점을 설정함 |
| 검증기 | 명령 경로와 메모리 접근을 검사해 적재 가능 여부를 판정함 |
| eBPF 프로그램 | 네트워크 훅에서 이벤트를 필터링·집계·기록함 |
| eBPF 맵 | 흐름 상태·카운터·설정값을 커널과 사용자 공간이 공유함 |
| 링 버퍼 | 선택한 이벤트를 커널에서 사용자 공간으로 전달함 |
| 사용자 공간 수집기 | 이벤트를 메트릭·로그·흐름 정보로 변환해 저장함 |

```text
로더 -> 검증기 -> eBPF 프로그램 --부착--> 커널 훅
                                           ^
네트워크 이벤트 ---------------------------+
                                           +-> 맵·링 버퍼 -> 사용자 공간 수집기
```

> 요약: 검증된 eBPF 프로그램이 커널 훅에서 이벤트를 선별하고 맵·링 버퍼로 수집기에 전달함.

## Ⅴ. 원리 및 절차 흐름도

```text
프로그램 적재 -> 안전성 검증 -> 커널 훅 부착 -> 이벤트 실행 -> 맵·링 버퍼 기록 -> 수집
```

1. **프로그램 적재**: 로더가 eBPF 명령과 맵 정의를 커널에 전달함
2. **안전성 검증**: 검증기가 제어 흐름·레지스터·메모리 접근을 검사함
3. **훅 부착**: 승인된 프로그램을 소켓·tracepoint·XDP·TC 지점에 연결함
4. **이벤트 실행**: 패킷·연결·시스템 호출이 훅을 지날 때 프로그램을 실행함
5. **이벤트 전달**: 집계값은 맵에 저장하고 선택 이벤트는 링 버퍼로 전송함
6. **사용자 공간 수집**: 수집기가 이벤트를 서비스·Pod·노드 문맥으로 변환함

> 요약: 검증된 프로그램을 커널 훅에 부착한 뒤 네트워크 이벤트를 맵·링 버퍼로 수집함.

## Ⅵ. 실무 사례

1. 컨테이너 노드는 eBPF로 TCP 재전송을 수집하고 Pod별 재전송률·연결 지연을 확인함
2. DNS 장애 분석은 소켓 이벤트를 서비스와 연결하고 질의 실패율·응답 지연을 확인함

## Ⅶ. 결론

- eBPF 네트워크 관측은 커널·워크로드 문맥이 필요하고 훅 범위·권한·수집 부하를 통제할 때 적용함
