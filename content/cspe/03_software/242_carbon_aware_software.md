# 📖 【암기용】 개념 완전 이해

> 목적: 탄소 인지 소프트웨어를 처음 봐도 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 전력망 탄소 집약도에 맞춰 실행 시간·장소·자원량을 조정하는 소프트웨어
- **왜 필요한가**: 같은 코드를 실행해도 석탄 발전 비중이 높은 시간과 재생에너지 비중이 높은 시간의 gCO2e/kWh가 다르다. 탄소 인지 설계는 이 차이를 운영 정책에 반영한다.
- **핵심 직관**: 급하지 않은 일을 전기가 덜 탄소 집약적인 시간과 지역으로 미루거나 옮기는 스케줄러이다.

## 깊이 이해
- **배경·문제의식**: 배치, 모델 학습, 이미지 변환처럼 시간 여유가 있는 작업은 즉시 실행할 필요가 없다. 탄소 인지 소프트웨어는 탄소 예보 API, 워크로드 SLA, 리전 배치 정책을 결합해 gCO2e/job을 낮춘다.
- **작동 원리**: 작업별 deadline, 데이터 위치, 리전 후보, 전력 탄소 계수를 입력으로 받아 실행 시점·지역을 선택한다. 지연 허용이 0초인 결제 API는 제외하고, 배치 작업은 2시간 내 완료 조건으로 이동 가능하다.
- **비유**: 세탁기를 전기 요금과 전력 탄소가 낮은 시간에 돌리는 예약 기능과 같다. 단, 업무 마감 시간과 데이터 주권 제약을 함께 본다.
- **구체 예시**: 로그 집계 배치를 00:00 즉시 실행에서 03:00~05:00 탄소 집약도 250gCO2e/kWh 구간으로 옮기면 500gCO2e/kWh 구간 대비 작업당 배출량이 절반 수준이 된다.
- **흔한 오해·주의점**: 모든 서비스를 늦추는 방식이 아니다. 사용자 요청 경로는 SLO 우선, 지연 허용 배치와 비동기 작업만 정책 대상이다.

## 연결 개념
- Green Software SCI — 탄소 인지 정책 효과를 gCO2e/unit으로 검증
- Job Scheduler — deadline 기반 배치 실행 시점 결정
- Data Residency — 국가·리전 이동 가능 여부 제약

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 탄소 인지 문제는 시간 이동, 지역 이동, 자원 조정 중 어떤 선택이 SLO와 규제를 만족하는지 판단하는 답안으로 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Carbon-Aware Software는 탄소 집약도 신호를 애플리케이션 스케줄링·배치·오토스케일링 정책에 반영하는 설계 방식이다.
> 2. **가치**: 지연 허용 워크로드를 저탄소 시간·리전으로 이동해 gCO2e/job을 줄이고, 사용자 경로는 SLO 기준으로 보호한다.
> 3. **판단 포인트**: deadline, 데이터 위치, 리전 규제, 탄소 예보 정확도, 비용·지연 트레이드오프를 함께 검토한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 지속가능 운영 설계 확인 | 시간 이동, 지역 이동, 수요 조정 | 모든 트래픽을 지연시키는 답안 |
| 클라우드 제약 판단 확인 | 데이터 주권, 지연시간, 리전별 계수 | 리전 이동 시 개인정보·규제 누락 |
| 운영 지표 연결 확인 | gCO2e/job, deadline miss, p95 | 탄소만 보고 SLO를 배제 |

> 요약: 탄소 인지 소프트웨어는 지연 허용 작업에 한정해 탄소 계수와 업무 마감 조건을 함께 최적화하는 운영 설계이다.

---

## Ⅰ. 개요 및 필요성

탄소 인지 소프트웨어는 전력망 탄소 신호를 반영해 실행 정책을 바꾸는 설계이다. 클라우드 리전과 시간대별 gCO2e/kWh 차이가 커지면서, 동일한 워크로드도 운영 시점에 따라 배출량이 달라진다. 기술사는 SLO와 규제를 만족하는 범위에서 탄소 신호를 적용해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Carbon Signal API -> Policy Engine -> Workload Classifier
                  -> Scheduler / Router / Autoscaler -> Metrics
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Carbon Signal API | 리전·시간별 gCO2e/kWh 현재값·예보 제공 | Electricity Maps, WattTime 등 |
| Workload Classifier | 실시간·지연 허용·배치 작업 분류 | deadline, SLO, 데이터 위치 |
| Policy Engine | 탄소·비용·지연 조건을 정책으로 결정 | 우선순위와 제외 조건 명시 |
| Scheduler/Router | 실행 시간·리전·자원량 조정 | Kubernetes, queue worker 연계 |

> 요약: 탄소 인지 구조는 탄소 신호를 업무 분류와 정책 엔진에 넣고 스케줄러가 실행 위치와 시점을 선택한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 접수 -> SLO/deadline 판정 -> 탄소 계수 조회
-> 실행 후보 평가 -> 스케줄/라우팅 -> SCI 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 워크로드를 실시간 API와 배치로 분류 | SLO p95, deadline 보유 |
| 2 | 리전별 탄소 계수와 비용 조회 | 계수 갱신 주기 5~15분 |
| 3 | deadline 내 최저 gCO2e 후보 선택 | deadline miss 0.1% 이하 |
| 4 | 실행 후 gCO2e/job, p95, 비용 기록 | SCI 기준선 대비 비교 |

> 요약: 실행 후보는 탄소 계수만이 아니라 deadline과 SLO를 만족하는 조합으로 선택한다.

---

## Ⅳ. 특징

| 구분 | 일반 스케줄링 | 탄소 인지 스케줄링 | 수치 판단 |
|:---|:---|:---|:---|
| 기준 | 비용, 자원 여유 | gCO2e/kWh, deadline, SLO | gCO2e/job 10~30% 감소 목표 |
| 대상 | 모든 작업 동일 정책 | 지연 허용 작업 중심 | 결제 API p95 200ms 유지 |
| 제약 | 리소스 한도 | 데이터 주권·리전 지연 추가 | 리전 이동 RTT 100ms 이하 |

> 요약: 탄소 인지 방식은 배치·비동기 작업에 우선 적용하고 사용자 요청 경로는 p95와 오류율 기준으로 보호한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 시간 | 즉시 실행 | deadline 내 지연 실행 | 배치 마감 2시간 이상일 때 |
| 지역 | 단일 리전 고정 | 저탄소 리전 후보 평가 | 데이터 주권과 RTT 조건 만족 시 |
| 자원 | 고정 용량 | 탄소 계수 기반 스케일 조정 | 큐 적체와 SLO 동시 만족 시 |

> 요약: deadline과 데이터 이동 제약이 느슨한 작업일수록 탄소 인지 정책의 적용 가치가 커진다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 마감 초과 | 예보 오류, 큐 적체 | latest start time 계산, fallback 실행 | deadline miss 0.1% 이하 |
| 규제 위반 | 리전 이동 정책 누락 | 데이터 등급별 허용 리전 목록 | 정책 위반 0건 |
| 비용 증가 | 저탄소 리전 단가 상승 | 비용 상한, 예약 인스턴스 병행 | job당 비용 10% 이내 증가 |

> 요약: 주요 리스크는 마감 초과와 리전 규제이며, fallback과 허용 리전 정책으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탄소 | gCO2e/job 기준선 대비 10% 이상 감소 | SCI 대시보드 |
| SLO | 실시간 API p95 200ms, 오류율 0.1% 이하 | APM, synthetic test |
| 스케줄 | deadline miss 0.1% 이하 | 큐 로그, 작업 이력 |

> 요약: 탄소 인지 도입은 탄소 지표, SLO, deadline miss를 함께 만족할 때 운영 기준을 통과한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 워크로드를 실시간·지연 허용·장기 배치로 분류하고 지연 허용 작업에 deadline 메타데이터 부여
2. Carbon Signal API를 스케줄러에 연동해 리전별 gCO2e/kWh와 비용 상한을 정책 엔진에서 평가
3. 배치 실행 후 gCO2e/job, deadline miss, p95를 릴리스 대시보드에 기록하고 월 1회 정책 보정

**결론 (2줄):**
- 기술사 판단: 사용자 경로는 SLO 우선, 배치·비동기 경로는 탄소 신호 우선으로 분리해야 한다
- 향후 방향: Kubernetes scheduler, serverless queue, AI 학습 파이프라인에 carbon-aware policy가 기본 운영 옵션으로 결합된다
