## Ⅰ. 개요
- 정의: 개인이 자신의 데이터를 주도적으로 관리하고 제3자에게 제공하는 체계임
- 배경: 데이터 경제 시대에 개인의 정보 주권 회복 및 데이터 이동권 보장 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 데이터 이동권 | 전송요구권 | 매우높음 |
| 보안 | API 방식, PDS | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ 정보 주체 ] --- (전송요구) ---> [ 정보 보유자 (금융/공공) ]
       |                                |
  [ 정보 수용자 (MyData 사업자) ] <--- (데이터 전송) ---+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 전송요구권 | 본인 정보를 다른 곳으로 옮기도록 요구할 권리 | 계좌 번호 이동 |
| 마이데이터 사업자 | 본인 인증 후 흩어진 정보를 통합 관리하는 기업 | 자산 관리 비서 |
| API 방식 | 스크래핑 대신 표준 규격으로 안전하게 데이터 연동 | 보안 통로 |

> 요약: 정보 주체가 전송 대상·항목·수신자를 정하고 본인 데이터를 이전하도록 요구함

## Ⅲ. 절차
- ASCII 흐름도
  [가입 및 동의] -> [정보 선택] -> [전송 및 수집] -> [맞춤 서비스 제공]
    (본인 인증)       (범위 설정)      (표준 API)        (초개인화)

- 4단계 설명
1. 인증/동의: 통합 인증을 통해 본인임을 확인하고 정보 제공 동의를 수행함
2. 전송요구: 여러 기관에 흩어진 정보를 한곳으로 모아달라고 요청함
3. 통합수집: 기관 간 표준 API와 인증·암호화 절차로 데이터 전송함
4. 서비스제공: 수집 범위와 이용 동의에 따라 금융·건강 관리 서비스 제공함

> 요약: 정보 주체의 명확한 의사결정에 기반하여 안전하게 데이터를 유통함

## Ⅳ. 문제점
- 특정 기업으로의 데이터 쏠림 현상 및 개인정보 유출 시 파급 효과가 매우 큼
- 데이터 유통 비용 부담 주체에 대한 갈등 및 데이터 표준화 수준의 격차 존재함

## Ⅴ. 개선방안
- (단기) 전용 네트워크 및 강화된 보안 가이드라인 준수 여부를 상시 점검함
- (중기) 데이터 전송 수수료 체계를 합리화하여 생태계 참여자 간 상생 도모함
- (장기) 개인정보 저장소(PDS) 보급으로 개인이 직접 데이터를 저장/통제함

## Ⅵ. 전망
- 금융 위주에서 의료, 교육, 통신 등 전 산업 분야로 마이데이터가 확산될 것임
- 자기 주권 신원 증명(DID) 기술과 결합하여 완벽한 '디지털 주권' 시대가 열림
