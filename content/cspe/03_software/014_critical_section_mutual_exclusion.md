# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 임계 구역과 상호 배제는 **여러 프로세스·스레드가 공유 자원에 접근하는 코드 영역(임계 구역)에 한 번에 하나만 들어가도록 통제(상호 배제)하는 동시성 제어의 기본 원리**로, 이를 만족하는 해법은 소프트웨어(Peterson·Dekker)·하드웨어(test-and-set)·OS 지원(세마포어)으로 나뉜다.
- **왜 필요한가**: 공유 변수를 둘 이상이 동시에 읽고 쓰면 실행 순서에 따라 결과가 달라지는 경쟁 상태(Race Condition)가 생겨 데이터가 깨진다. 임계 구역 진입을 한 번에 하나로 강제해야 무결성이 지켜진다.
- **핵심 직관**: 한 칸짜리 회의실에 예약 규칙을 세우는 문제다. "동시에 두 명이 못 들어감(상호 배제), 아무도 없으면 원하는 사람이 들어감(진행), 무한정 기다리는 사람이 없음(유한 대기)" 세 조건을 모두 지키는 예약 방식을 찾는 것이 상호 배제 해법이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 답안용에 나오는 상호 배제 조건·해법 표기를 비유와 함께 먼저 세운다. 맨 위가 이 주제의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 상호 배제 (상위 키워드) | 임계 구역에 한 번에 하나의 실행 흐름만 진입 | 한 칸 회의실은 한 명만 |
| 임계 구역 (Critical Section) | 공유 자원을 접근하는 보호 대상 코드 영역 | 예약이 필요한 회의실 내부 |
| 경쟁 상태 (Race Condition) | 동시 접근으로 결과가 실행 순서에 좌우됨 | 두 사람이 동시에 잔액 갱신해 값 꼬임 |
| 진입 구역 (Entry Section) | 임계 구역 진입 전 허가를 얻는 코드 | 회의실 문 앞 예약 확인 |
| 퇴출 구역 (Exit Section) | 임계 구역을 나오며 상태를 되돌리는 코드 | 나오며 예약 해제 |
| 진행 (Progress) | 아무도 안 쓰면 진입 희망자 중 하나는 반드시 진입 | 빈 회의실은 원하는 사람이 씀 |
| 유한 대기 (Bounded Waiting) | 진입 대기가 유한 횟수 내 보장, 기아 방지 | 무한정 밀리는 사람 없음 |
| Peterson 알고리즘 | 플래그+turn 변수로 2프로세스 상호 배제 SW 해법 | "나 쓸래" 표시 + 양보 순번표 |
| flag[] / turn | 진입 의사 배열 / 양보 순번 변수 | 손 들기 배열 / 순번 팻말 |
| Dekker 알고리즘 | 최초의 2프로세스 SW 상호 배제 해법 | Peterson의 원조, 양보 로직 복잡 |
| test-and-set (TAS) | 값을 1로 세팅하며 이전 값 반환하는 원자 명령 | 문패를 한 번에 뒤집고 원래 상태 확인 |
| Compare-and-Swap (CAS) | 값 비교 후 같으면 교체하는 원자 명령 | "빈칸이면 이름 써넣기"를 한 번에 |
| 원자성 (Atomicity) | 중간에 끼어들 수 없는 분리 불가 실행 | 반으로 쪼갤 수 없는 한 동작 |
| 바쁜 대기 (Busy-waiting) | 진입 조건을 루프로 반복 검사 (013 참조) | 문 앞에서 계속 확인 |

## 깊이 이해
- **배경·문제의식**: `count++` 한 줄도 기계어로는 읽기-증가-쓰기 3단계라, 두 스레드가 겹치면 한쪽 갱신이 사라진다(lost update). 이 구간이 임계 구역이며, 올바른 상호 배제 해법은 반드시 **상호 배제·진행·유한 대기** 세 조건을 동시에 만족해야 한다. 하나라도 빠지면 교착·기아·경쟁 상태가 남는다.
- **작동 원리(어떻게+왜)**:
  - **소프트웨어 해법(Peterson)**: 두 변수 `flag[i]`(내가 들어가고 싶다)와 `turn`(양보 순번)만으로 2프로세스 상호 배제를 달성한다. 진입 전 `flag[i]=true; turn=j;`로 "의사 표시 후 상대에게 순번 양보"하고, 상대가 원하고 순번이 상대일 때만 기다린다. 특별한 하드웨어 없이 세 조건을 모두 만족하는 것이 핵심 가치다. 단, 현대 CPU의 명령 재배열 때문에 메모리 배리어가 필요하다.
  - **하드웨어 해법(test-and-set·CAS)**: "검사와 설정을 한 번에" 수행하는 원자 명령을 CPU가 제공한다. `while(test-and-set(lock)) ;`로 락을 잡으면 중간에 끼어들 수 없어 상호 배제가 단순·확실하다. 소프트웨어 해법의 복잡한 양보 로직이 필요 없지만, 기본형은 유한 대기를 보장하지 못해 별도 큐가 필요하다.
  - **OS/언어 지원**: 세마포어·뮤텍스·모니터(012 참조)는 위 원자 명령을 토대로 대기 큐·소유권·조건 변수를 얹어 개발자가 저수준 로직을 직접 짜지 않게 한다.
- **비유**: 한 칸 회의실 예약이다. Peterson은 사람끼리 "나 쓸래" 팻말과 "네가 먼저 써" 순번표만으로 규칙을 지키는 신사협정, test-and-set은 회의실 문에 달린 자동 전자 잠금장치(누르는 순간 잠기고 남은 못 들어감)다. 전자는 장비가 필요 없고, 후자는 장비가 대신 확실히 막아준다.
- **구체 예시**: 은행 계좌 `balance -= 100`을 두 ATM 스레드가 동시에 하면, 둘 다 잔액 1000을 읽고 각각 900을 써 100이 증발한다. 임계 구역(읽기-계산-쓰기)을 Peterson이나 뮤텍스로 감싸면 한 번에 하나만 갱신해 800이 정확히 남는다. 리눅스 커널의 `spin_lock`은 test-and-set 계열 원자 명령으로 구현된다.
- **흔한 오해·주의점**: (1) **인터럽트 비활성화는 단일 CPU에서만 유효** — 멀티코어에서는 다른 코어가 여전히 접근하므로 상호 배제가 깨진다. (2) **바쁜 대기 자체는 상호 배제 조건이 아니다** — Peterson·TAS 모두 바쁜 대기를 쓰지만, 핵심은 세 조건 만족 여부다. (3) Peterson은 원론적으로 2프로세스용이며, N프로세스로 일반화하려면 빵집(Bakery) 알고리즘 등이 필요하다.

## 연결 개념
- 세마포어·뮤텍스·모니터(012 참조) — 상호 배제 세 조건을 OS·언어 차원에서 구현한 도구
- 스핀락 vs 뮤텍스(013 참조) — 상호 배제 대기 중 CPU 소비 방식(바쁜 대기 vs 블로킹)
- 교착상태(009 참조)·기아(011 참조) — 진행·유한 대기 조건이 깨질 때 나타나는 부작용

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 임계 구역은 공유 자원 접근 보호 코드 영역이고, 상호 배제는 그 영역에 한 번에 하나만 들이는 원리로 동시성 제어의 기초임.
> 2. **가치**: 올바른 해법은 상호 배제·진행·유한 대기 세 조건을 동시에 만족해야 경쟁 상태·교착·기아를 모두 막음.
> 3. **판단 포인트**: 하드웨어 지원이 없으면 SW 해법(Peterson), 멀티코어 성능이 중요하면 HW 원자 명령(test-and-set·CAS)이 적합함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 상호 배제 세 조건 | 상호 배제·진행·유한 대기 | 유한 대기(기아 방지) 조건 누락 |
| SW·HW 해법 구분 | Peterson(flag+turn) vs test-and-set·CAS | 인터럽트 비활성화를 멀티코어에 적용 단정 |
| 해법별 적용 판단 | HW 지원·프로세스 수·성능 기준 | 바쁜 대기를 상호 배제 조건으로 혼동 |

> 요약: 임계 구역 문제를 세 조건으로 정의하고, SW(Peterson)·HW(test-and-set) 해법을 지원 여부·성능 기준으로 구분해 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 공유 자원 접근 코드 영역(임계 구역)에 한 번에 하나만 진입시키는 동시성 제어 원리임
- 배경: 읽기-계산-쓰기가 겹치면 갱신 손실(경쟁 상태)로 데이터 무결성이 깨짐
- 필요성: 상호 배제·진행·유한 대기를 동시에 만족하는 해법으로 정확성과 기아 방지를 함께 확보해야 함

## Ⅱ. 구조 및 구성요소

선형 구조도 (임계 구역 코드 구성 + 해법 계열):

    do {
      진입 구역(Entry) - 진입 허가 획득
        -> 임계 구역(Critical Section) - 공유 자원 접근
        -> 퇴출 구역(Exit) - 허가 반납
        -> 나머지 구역(Remainder) - 무관 코드
    } while(true)
    해법 계열: SW(Peterson/Dekker) / HW(test-and-set/CAS) / OS(세마포어·뮤텍스·모니터)

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 진입 구역 | 임계 구역 진입 허가 획득 | 상호 배제 로직이 위치 |
| 임계 구역 | 공유 자원을 실제 접근 | 한 번에 하나만 실행 |
| 퇴출 구역 | 허가 반납·상태 복원 | flag 해제·unlock 등 |
| SW 해법(Peterson) | flag[]+turn으로 2프로세스 배제 | HW 지원 불필요, 배리어 필요 |
| HW 해법(test-and-set·CAS) | 원자 명령으로 검사·설정 일괄 | 단순·확실, 유한 대기 별도 보강 |

> 요약: 임계 구역 코드는 진입·임계·퇴출·나머지로 나뉘며, 진입 로직을 SW·HW·OS 세 계열 해법으로 구현함.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도 (Peterson 2프로세스 진입, i·j는 두 프로세스):

    Pi: flag[i]=true -> turn=j (상대에게 양보)
      -> while(flag[j] && turn==j) 대기 (상대가 원하고 순번이 상대면 양보)
      -> 임계 구역 진입 -> flag[i]=false (퇴출)
    HW 대안: while(test-and-set(lock)) 대기 -> 임계 구역 -> lock=false

- 1단계 [의사 표시]: 프로세스 Pi가 `flag[i]=true`로 진입 의사를 밝히고 `turn=j`로 상대에게 순번을 양보함
- 2단계 [진입 판정]: 상대 Pj도 원하고(`flag[j]=true`) 순번이 상대(`turn==j`)면 Pi는 대기하고, 아니면 진입함
- 3단계 [임계 구역 실행]: 조건을 통과한 하나의 프로세스만 공유 자원을 접근함
- 4단계 [퇴출]: Pi가 `flag[i]=false`로 의사를 거두면 대기 중인 Pj가 진입함

> 요약: 진입 전 의사 표시와 순번 양보로 동시 진입을 배제하고, 퇴출 시 플래그를 내려 대기자를 진입시켜 세 조건을 만족함.

## Ⅳ. 특징

- 세 조건 필수성: 상호 배제·진행·유한 대기 중 하나만 빠져도 경쟁 상태·교착·기아가 남음
- SW 해법의 이식성: Peterson·Dekker는 특수 하드웨어 없이 순수 코드로 동작해 원리 이해에 유용함
- HW 해법의 단순성: test-and-set·CAS는 검사·설정을 원자적으로 묶어 로직이 간결하고 멀티코어에 유효함
- 인터럽트 비활성화의 한계: 단일 CPU에서만 상호 배제가 되고 멀티코어에서는 무력함
- 현대적 제약: CPU 명령 재배열 탓에 SW 해법은 메모리 배리어 없이는 오동작할 수 있음

## Ⅴ. 심화 비교 및 적용 판단

상호 배제 해법을 소프트웨어·하드웨어 축으로 대조함(대기 방식 스핀 vs 블로킹은 013, OS 도구는 012 참조).

| 구분 | SW 해법(Peterson·Dekker) | HW 해법(test-and-set·CAS) |
|:---|:---|:---|
| 하드웨어 지원 | 불필요(순수 코드) | 필요(원자 명령) |
| 로직 복잡도 | 높음(flag+turn 양보) | 낮음(원자 명령 한 줄) |
| 프로세스 수 | 2프로세스 기본(N은 Bakery) | N프로세스 자연 확장 |
| 상호 배제 | 세 조건 만족 | 상호 배제 확실, 유한 대기 별도 보강 |
| 멀티코어 유효성 | 배리어 필요 | 유효(원자성 하드웨어 보장) |
| 대표 활용 | 원리 학습·임베디드 | 커널 스핀락·lock-free 자료구조 |

> 요약: 하드웨어 지원이 없거나 원리 이해가 목적이면 SW 해법, 멀티코어 성능·N프로세스 확장이 필요하면 HW 원자 명령이 적합함.

**리스크·대응:**
- 갱신 손실(경쟁 상태) — 읽기-계산-쓰기 겹침 — 임계 구역을 락/원자 명령으로 감싸 상호 배제 강제
- 기아 — 특정 프로세스 무한 대기 — 유한 대기 보장(turn 교대·대기 큐·Bakery 번호표) 적용
- 명령 재배열 오동작 — CPU/컴파일러 최적화로 순서 뒤바뀜 — 메모리 배리어·volatile·atomic 사용

**점검 지표:**
- 정확성: 경쟁 상태 발생 건수(0 목표), 갱신 손실 검출 여부
- 성능: 진입 대기 시간(p99), 임계 구역 평균 점유 시간

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 저수준 커널 보호: 짧은 공유 구조 접근에 test-and-set·CAS 기반 스핀락(spin_lock)으로 상호 배제 적용
2. 응용 계층 동기화: 개발자가 직접 Peterson을 짜기보다 OS 제공 뮤텍스·모니터(std::mutex, Java synchronized)로 세 조건을 위임(012 참조)
3. 고성능 무잠금 설계: 경합이 심한 카운터·큐에 CAS 기반 lock-free 자료구조로 락 없이 원자적 갱신 적용

**결론:**
- 기술사 판단: 하드웨어 원자 명령이 있으면 test-and-set·CAS 기반 해법, 없거나 2프로세스 원리 구현이면 Peterson을 선택하되 실무는 OS 도구로 위임함
- 향후 방향: 멀티코어 확산으로 락 경합을 회피하는 CAS 기반 lock-free·wait-free 알고리즘과 트랜잭셔널 메모리(HTM)로 상호 배제가 발전함
