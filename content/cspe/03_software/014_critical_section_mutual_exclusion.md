## Ⅰ. 개요
- **정의**: 공유 자원에 동시 접근 시 데이터 일관성을 보장하기 위해 한 프로세스만 진입을 허용하는 기법
- **배경/필요성**: 다중 프로세스 환경에서 경쟁 조건(race condition)에 의한 데이터 훼손을 방지할 필요가 있음
- **비유**: 1인용 화장실에 한 명만 들어가고 나머지는 줄을 서는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병행 제어 원리 이해 | 상호배제 3요건(ME, Progress, Bounded Wait) | 데드락과 상호배제를 혼동하면 감점 |

> 요약: 공유 자원 접근을 직렬화하여 경쟁 조건을 방지하는 동기화 메커니즘임

## Ⅱ. 구성요소
```text
Process A --+                         +-- Process A (in CS)
            |-- Entry Section(Lock) --|
Process B --+                         +-- Process B (waiting)
                                      |
                                      +-- Exit Section(Unlock)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 임계구역(CS) | 공유 자원을 접근하는 코드 영역 | 1인용 화장실 내부 |
| 진입 구역 | 잠금을 획득하여 CS 진입 가능 여부를 판단함 | 문 앞에서 잠금 확인 |
| 퇴출 구역 | 잠금을 해제하여 대기 프로세스에 진입 기회를 제공함 | 나오면서 문 잠금 해제 |
| 동기화 도구 | 뮤텍스, 세마포어, 모니터 등 상호배제 구현 수단 | 열쇠, 번호표, 안내원 |

> 요약: 진입·퇴출 구역과 동기화 도구로 임계구역 접근을 제어함

## Ⅲ. 절차
```text
Lock 요청 --> CS 진입 --> 공유자원 접근 --> Unlock(해제)
```
- 1단계: 프로세스가 `lock` 연산으로 임계구역 진입을 요청함
- 2단계: 잠금 획득 시 임계구역에 진입하고, 실패 시 대기(spin/block)함
- 3단계: 공유 자원에 대한 읽기·쓰기를 수행함
- 4단계: `unlock` 연산으로 잠금을 해제하고 대기 프로세스에 진입 기회를 부여함

> 요약: 잠금 요청 → 진입 → 자원 접근 → 해제 순서로 동작함

## Ⅳ. 문제점
- 교착 상태: 둘 이상의 프로세스가 서로의 잠금 해제를 무한 대기함
- 우선순위 역전: 낮은 우선순위 프로세스가 CS를 점유하여 높은 우선순위 프로세스가 차단됨
- 성능 저하: 과도한 잠금 경합 시 직렬화로 병렬성이 감소함

> 요약: 교착 상태, 우선순위 역전, 잠금 경합에 의한 성능 저하가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 잠금 순서 규약과 타임아웃을 적용하여 교착 상태를 예방함
2. 중기: 우선순위 상속(Priority Inheritance) 프로토콜로 우선순위 역전을 해소함
3. 장기: Lock-free·Wait-free 자료구조로 잠금 경합 자체를 제거함

> 요약: 잠금 규약 → 우선순위 상속 → Lock-free 전환 순으로 개선함

## Ⅵ. 전망
- 발전 방향: 멀티코어 확산으로 세밀한 잠금(fine-grained lock)과 비차단 알고리즘 채택이 증가함
- 기술사적 판단: 병행 프로그래밍의 정확성을 좌우하는 기본 원리로 중요도가 지속됨
- 기술사 제언: 동기화 기법 선택 시 워크로드 특성별 경합 수준을 분석하여 적합한 도구를 적용할 필요가 있음
