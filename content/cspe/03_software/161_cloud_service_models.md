## 미리 알고가기

- IaaS는 서버·스토리지·네트워크를 제공하고 소비자가 운영체제부터 관리하는 서비스임
- PaaS는 운영체제·런타임·미들웨어를 제공하고 소비자가 애플리케이션을 배포하는 서비스임
- SaaS는 공급자가 운영하는 애플리케이션을 소비자가 설정해 사용하는 서비스임
- 책임 경계는 공급자와 소비자가 각각 운영·보호해야 할 계층을 나누는 기준임
- 제어 범위가 넓을수록 구성 자유도와 소비자 운영 책임이 함께 늘어남
- 서비스 모델이 바뀌어도 데이터 분류·계정·접근 권한은 소비자 책임으로 남음

## 작성 근거(검토용)

- 서비스 모델은 제공 계층보다 소비자 제어 범위와 운영 책임이 선택을 가르므로 두 축을 중심에 둠
- 비교표의 제공 단위·배포 방식·변경 범위를 실무 사례에서 회수하고 소비자 제어·공급자 운영 범위는 Ⅳ 책임 매트릭스에서 계층별로 다룸
- Ⅴ절은 요구 분석부터 서비스 모델 선택·책임 확정·통제 검증까지의 의사결정 절차로 구성함
- 제목부터 결론까지 5회 전수 검수하여 표의 대응 수준과 단어·조사·동사 결합을 교정함

## Ⅰ. 개요

- **정의/개념**: 클라우드 서비스 모델은 공급자 제공 계층과 소비자 제어 계층에 따라 IaaS·PaaS·SaaS를 구분하는 체계임
- **배경/필요성**: 업무 요구에 맞는 제어 범위와 운영 책임을 정하기 위해 서비스 계층별 책임 경계가 필요함

### 쉽게 이해하기 (학습용)
- IaaS·PaaS·SaaS는 필요한 기능보다 어디까지 직접 운영할 것인지를 정하는 선택지임

## Ⅱ. 특징

- 서버부터 애플리케이션까지 어느 계층을 서비스로 제공하는지에 따라 모델이 구분됨
- 상위 계층을 공급자가 운영할수록 소비자의 패치·용량·장애 대응 범위가 줄어듦
- 소비자 제어 범위가 넓을수록 운영체제·런타임·미들웨어 구성을 직접 변경할 수 있음
- 동일 공급자에서도 서비스별 책임 경계가 달라 계약·구성·감사 증적을 따로 확인해야 함

### 쉽게 이해하기 (학습용)
- 공급자에게 맡기는 계층이 늘면 운영 부담은 줄지만 직접 바꿀 수 있는 범위도 좁아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | IaaS | PaaS | SaaS |
|:---|:---|:---|:---|
| 제공 단위 | 가상 서버·스토리지·네트워크 | 애플리케이션 실행 플랫폼 | 완성된 업무 애플리케이션 |
| 배포 방식 | VM 이미지와 인프라 구성 배포 | 소스·패키지·컨테이너 배포 | 사용자 계정과 서비스 설정 |
| 변경 범위 | 운영체제부터 직접 변경 | 제공 런타임과 확장 지점 안에서 변경 | 공급자가 제공한 기능과 설정만 변경 |

> 요약: IaaS에서 SaaS로 갈수록 제공 단위는 완성된 서비스로 바뀌고 소비자가 배포·변경할 수 있는 범위는 줄어듦.

### 쉽게 이해하기 (학습용)
- IaaS는 빈 사무실을 꾸미는 방식, PaaS는 설비가 갖춰진 공간, SaaS는 완성된 서비스를 쓰는 방식에 가까움

## Ⅳ. 구성요소 및 구조

| 계층 | 주요 대상 | 책임 판단 |
|:---|:---|:---|
| 물리 인프라 | 데이터센터·서버·스토리지·네트워크 | 모든 서비스 모델에서 공급자가 운영함 |
| 가상화 계층 | 하이퍼바이저·가상 네트워크 | 모든 서비스 모델에서 공급자가 운영함 |
| 운영체제·런타임 | 게스트 OS·언어 런타임 | IaaS는 소비자, PaaS·SaaS는 공급자가 운영함 |
| 미들웨어 | 웹 서버·DB 엔진 | IaaS는 소비자, PaaS·SaaS는 공급자가 운영함 |
| 애플리케이션 | 업무 로직·화면·API | SaaS는 공급자, IaaS·PaaS는 소비자가 관리함 |
| 데이터·계정 | 업무 데이터·사용자·접근 권한 | 모든 모델에서 소비자가 분류·권한·보존을 관리함 |
| 책임 매트릭스 | 계층별 운영·보안·증적 담당 | 계약과 서비스 문서로 책임자를 확정함 |

```text
소비자 제어 범위: IaaS(넓음) -> PaaS -> SaaS(좁음)
공급자 운영 범위: IaaS(좁음) -> PaaS -> SaaS(넓음)
```

> 요약: 서비스 계층을 따라 소비자 제어와 공급자 운영의 경계가 반대 방향으로 이동함.

### 쉽게 이해하기 (학습용)
- 운영 계층마다 공급자와 소비자 중 누가 패치·설정·증적을 맡는지 표로 확정해야 함

## Ⅴ. 원리 및 절차 흐름도

```text
업무 요구 분석 -> 제어·운영 범위 결정 -> 서비스 모델 선택 -> 책임 매트릭스 확정 -> 통제 검증
```

1. 데이터 규제·변경 자유도·운영 역량·출시 속도를 업무별로 확인함
2. 직접 제어할 계층과 공급자에게 맡길 계층을 구분함
3. IaaS·PaaS·SaaS 중 요구에 맞는 서비스 모델을 선택함
4. 계정·데이터·패치·로그의 수행자와 증적 보유자를 확정함
5. 배포 후 계약 범위와 실제 구성·운영 통제가 일치하는지 확인함

> 요약: 필요한 제어와 감당할 운영 책임을 대조해 모델을 선택하고 계층별 통제를 검증함.

### 쉽게 이해하기 (학습용)
- 직접 관리할 일과 맡길 일을 먼저 나눈 뒤 서비스 모델과 책임표를 정하는 순서임

## Ⅵ. 실무 사례

1. 기존 웹 서버는 IaaS로 이전하고 게스트 OS 패치 준수율·인스턴스 가동률을 확인함
2. API 개발 플랫폼은 PaaS 런타임을 표준화하고 배포 소요 시간·실패율을 확인함

### 쉽게 이해하기 (학습용)
- 같은 조직에서도 서버 이전은 IaaS, 빠른 애플리케이션 배포는 PaaS처럼 목적별로 다르게 선택할 수 있음

## Ⅶ. 결론

- 클라우드 서비스 모델은 필요한 제어 범위와 감당할 운영 책임을 기준으로 선택해야 함

### 쉽게 이해하기 (학습용)
- 가장 관리가 적은 모델이 아니라 업무에 필요한 통제와 운영 능력이 맞는 모델이 적합함
