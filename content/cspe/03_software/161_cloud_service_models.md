## 핵심 인사이트 (3줄 요약)
- 기업이 IT 시스템(서버, DB, 앱)을 구축할 때, **어디까지 클라우드 빌려주는 회사(AWS, MS)한테 맡기고, 어디서부터 내가 직접 관리할 것인가**를 나누는 3단계 책임 분담 모델.
- 빈 땅과 벽돌만 빌려줘서 내 맘대로 짓는 **IaaS**, 건물 뼈대와 가스/수도까지 다 해줘서 인테리어(코드)만 내가 하는 **PaaS**, 아예 풀옵션 호텔 방을 빌려서 몸만 들어가는 **SaaS**로 진화함.
- "서버를 직접 조립하는 노가다를 줄이고, 회사의 본업(비즈니스 로직)에만 집중하겠다"는 클라우드 컴퓨팅의 진화 방향을 보여주는 가장 근본적인 교양임.

## Ⅰ. 개요 및 필요성
- **개요**: 클라우드 컴퓨팅 환경에서 제공자(Provider)와 사용자(Consumer) 간의 관리 책임 범위를 기준으로 클라우드 서비스를 분류한 표준 모델 (NIST 정의).
- **필요성**: 과거 온프레미스 시대엔 기업이 서버 철통(하드웨어)부터 에어컨 온도, O/S 설치, 네트워크 선 연결, DB 세팅, 앱 개발까지 1부터 100까지 다 해야 했음(피자 굽기 비유). "우린 쇼핑몰 회사인데 왜 윈도우 보안 패치를 깔면서 밤을 새워야 하지? 하드웨어나 기본 인프라는 남한테 돈 주고 빌리고, 우리는 쇼핑몰 코드 짜는 데만 집중하자!"라는 아웃소싱의 극대화에서 탄생함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **0. On-Premise (직접 구축)**:
  - 하드웨어 ➡️ OS ➡️ 미들웨어 ➡️ 런타임 ➡️ 데이터 ➡️ 어플리케이션까지 **100% 고객이 관리**. (IDC 센터).
- **1. IaaS (Infrastructure as a Service)**:
  - **제공자가 관리**: 네트워킹, 스토리지, 서버 하드웨어, 가상화(Hypervisor).
  - **고객이 관리**: OS부터 그 위 전부 (Windows/Linux 설치, 패치, 앱 등).
  - **특징**: "깡통 가상 서버(VM)를 빌려줄게." 자유도는 최고지만, OS 패치 같은 관리가 귀찮음. (예: AWS EC2, Google Compute Engine).
- **2. PaaS (Platform as a Service)**:
  - **제공자가 관리**: IaaS 전부 + OS, 미들웨어, 런타임 환경 (Java, Python 세팅).
  - **고객이 관리**: 내가 짠 애플리케이션 코드와 데이터.
  - **특징**: "환경 다 세팅해 놨어! 너는 코드만 업로드해!" 개발 속도가 극단적으로 빠름. (예: AWS Elastic Beanstalk, Heroku).
- **3. SaaS (Software as a Service)**:
  - **제공자가 관리**: 밑바닥부터 맨 꼭대기 애플리케이션까지 **100% 제공자가 관리**.
  - **고객이 관리**: 그냥 브라우저 켜서 아이디 치고 서비스 이용(소비)만 함.
  - **특징**: "다 만들어진 소프트웨어를 월정액 내고 써!" 커스텀(자유도)은 불가능함. (예: 구글 워크스페이스, 슬랙, 세일즈포스).

```text
[ 피자로 비유하는 클라우드 서비스 모델 (Pizza as a Service) ]

 🍕 [ On-Premise (홈메이드 피자) ]
 - 내가 도우 반죽하고, 토핑 얹고, 오븐 사고, 가스비 내고, 식탁까지 다 차림. (전부 내 책임).

 🚚 [ IaaS (냉동 피자 굽기) ]
 - 마트에서 냉동 피자(가상화된 깡통 서버)를 사 옴.
 - 우리 집 오븐과 가스로 굽고 내 식탁에서 먹음. (인프라만 빌림).

 🛵 [ PaaS (피자 배달) ]
 - 도미노 피자에서 다 구워진 피자를 배달시킴 (OS, 런타임 다 됨).
 - 나는 식탁이랑 콜라(내 코드, 데이터)만 준비해서 먹음. (개발 환경 빌림).

 🍽️ [ SaaS (피자 레스토랑 외식) ]
 - 식당 가서 남이 구워준 피자를 먹고, 설거지도 안 하고 돈만 내고 나옴! (풀옵션 구독).
```

## Ⅲ. 비교 및 연결
| 구분 | IaaS (인프라) | PaaS (플랫폼) | SaaS (소프트웨어) |
|---|---|---|---|
| **제공 내용** | 가상 머신(VM), 스토리지, 네트워크 | 앱 배포 환경 (OS, 런타임 포함) | 완성된 웹 소프트웨어 응용프로그램 |
| **주요 타겟 고객**| 시스템 엔지니어, 인프라 아키텍트 | **소프트웨어 개발자 (코더)** | **일반 비즈니스 사용자 (End-User)** |
| **제어권 (자유도)**| 가장 높음 (OS 마음대로 주무름) | 중간 (코드는 내 맘대로, OS는 터치 불가) | 가장 낮음 (화면 세팅 정도만 가능) |
| **대표 서비스** | AWS EC2, Azure VM | Heroku, Google App Engine | Salesforce, Microsoft 365, Slack |

## Ⅳ. 실무 적용 및 기술사 판단
- **클라우드 네이티브로의 진화 (FaaS와 Serverless)**: 기술사는 최근 아키텍처 트렌드가 PaaS를 넘어서 **FaaS(Function as a Service, 일명 서버리스)**로 가고 있음을 짚어야 함. AWS Lambda처럼 "서버의 존재조차 잊어버리고, 오직 내가 짠 '함수(Function)' 1개가 실행된 0.1초만큼의 돈만 내는" 궁극의 자동화 환경이 백엔드 아키텍처(Event-driven)의 대세가 됨.
- **Lock-in(종속성) 회피 전략**: PaaS를 쓰면 개발 속도는 빠르지만, 특정 클라우드 벤더(AWS)의 환경에 코드가 종속되어 나중에 GCP로 이사 갈 때 코드를 다 갈아엎어야 하는 '벤더 락인(Vendor Lock-in)'이 심함. 실무 아키텍트는 이를 피하기 위해 IaaS 위에 직접 도커(Docker)와 쿠버네티스(Kubernetes)를 올려, 환경 자체를 컨테이너로 포장해 클라우드 간 이사가 자유로운 **CaaS(Container as a Service)** 전략을 주로 택함.

## Ⅴ. 기대효과 및 결론
- "IT 인프라를 소유(Capital Expenditure, 자산)하는 것에서, 전기나 수도처럼 구독하여 소비(Operational Expenditure, 비용)하는 것"으로 전 세계 비즈니스 경제 모델을 뒤바꿔 놓음.
- 기업은 더 이상 서버가 고장 날까 봐 밤잠을 설칠 필요 없이, 오직 자신의 비즈니스 아이디어(코드와 서비스)를 혁신하는 데에만 100%의 역량을 쏟을 수 있게 한 클라우드 혁명의 기본 나침반임.

### 📈 관련 키워드 및 발전 흐름도
- 자체 전산실 (IDC) ➡️ 가상화(Hypervisor) 기술의 발달 ➡️ Amazon의 EC2(IaaS) 상용화 대박 ➡️ 개발 생산성을 위한 PaaS 등장 ➡️ 기업용 SW의 SaaS화 (구독 경제) ➡️ NoOps(운영 제로)를 향한 Serverless/FaaS 진화

### 👶 어린이를 위한 3줄 비유 설명
1. **IaaS**는 '자동차 렌트'예요. 차는 빌려주지만 운전, 주유, 세차는 다 내가 해야 하죠.
2. **PaaS**는 '택시'예요. 기사님이 운전과 주유(서버 환경)를 다 해주니까 나는 목적지(내 프로그램 코드)만 말하면 편하게 갈 수 있어요.
3. **SaaS**는 '놀이공원 버스'예요. 아예 목적지(완성된 프로그램)가 딱 정해져 있어서, 나는 표(월정액)만 끊고 자리에 앉아 신나게 놀기만 하면 된답니다!
