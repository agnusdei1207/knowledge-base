## Ⅰ. 개요
- 정의: Cyclomatic Complexity의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  V(G) = E - N + 2
  (E: Edges, N: Nodes)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 노드 (Node) | 실행 가능한 문장이나 명령 블록 | 정거장 |
| 에지 (Edge) | 명령 간의 제어 흐름 경로 | 도로 |
| 선형 독립 경로 | 분기 조건에 따라 결정되는 고유 경로 | 길 찾기 |

> 요약: 제어 흐름 그래프를 통해 논리적 복잡도를 측정하는 지표임.

## Ⅲ. 절차
- ASCII 흐름도
  Code -> Flow Graph -> Count E, N -> Calculate V(G)

1. 그래프 변환: 소스 코드를 제어 흐름 그래프로 시각화함.
2. 구성 요소 계산: 노드 수와 에지 수, 분기점(P) 식별함.
3. 복잡도 산출: E-N+2 또는 P+1 공식을 사용하여 계산함.
4. 위험도 평가: 10 이하(안전), 20 이상(복잡), 50 이상(불가) 판단함.

> 요약: 테스트 케이스 최소 수량 산정 및 코드 리팩토링 기준 제공임.

## Ⅳ. 문제점
- 단순 분기문 위주 측정으로 연산의 복잡도 반영은 미흡함.
- 물리적 코드 라인수와 복잡도가 반드시 비례하지는 않음.

## Ⅴ. 개선방안
- 인지 복잡도(Cognitive Complexity) 병행 활용으로 가독성 보완함.
- IDE 내 실시간 측정 기능을 통해 개발 단계에서 복잡도 제어함.

## Ⅵ. 전망
- 보안 취약점 발생 확률과의 상관관계 분석을 통한 보안 강화 활용됨.
- CSF: 복잡도 임계치를 빌드 실패 조건(Quality Gate)으로 설정임.
