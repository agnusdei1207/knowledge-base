## 미리 알고가기

- PACELC는 분할이 났을 때와 평상시를 나눠 보는 분산 저장소 판단 기준임
- 분할이 나면 가용성과 일관성 중 무엇을 더 지킬지 정해야 함
- 평상시에도 응답 속도와 일관성 사이에 비용 차이가 생김
- PC/EC는 일관성을 더 중시하는 성향이고 PA/EL은 가용성과 응답 속도를 더 중시하는 성향임

## Ⅰ. 개요

- **정의/개념**: PACELC 정리는 분산 시스템이 장애로 분할되면 가용성과 일관성 사이에서, 평상시에는 응답 속도와 일관성 사이에서 다시 선택하게 된다는 원리임
- **배경/필요성**: CAP만으로는 장애 순간의 판단은 설명할 수 있어도 평상시 지연 시간까지 설명하기 어려워 실제 서비스 설계에는 더 넓은 기준이 필요함

## Ⅱ. 특징

- 분할 장애 때의 판단과 정상 운영 때의 판단을 따로 본다는 점이 핵심임
- 강한 일관성을 유지할수록 복제 동기화 비용과 응답 지연이 커질 수 있음
- 낮은 지연을 우선하면 일부 읽기에서 최신 값이 늦게 보일 수 있음
- 같은 분산 저장소라도 업무별로 다른 PACELC 성향을 요구할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 정합성 우선형(PC/EC) | 응답 속도 우선형(PA/EL) |
|:---|:---|:---|
| 분할 시 선택 | 일관성을 먼저 지킴 | 가용성을 먼저 지킴 |
| 평상시 선택 | 일관성을 위해 더 기다림 | 빠른 응답을 위해 동기화를 줄임 |
| 장점 | 데이터 신뢰도가 높음 | 사용자 체감 속도가 좋음 |
| 잘 맞는 업무 | 결제, 재고, 핵심 기준 정보 | 피드, 추천, 대규모 조회 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 분할 시 정책 | 장애 때 요청을 막을지 계속 받을지 정함 |
| 평상시 응답 목표 | 어느 수준의 지연을 허용할지 정함 |
| 복제 동기화 방식 | 동기 복제인지 비동기 복제인지에 따라 일관성과 속도가 갈림 |
| 업무 등급 | 어떤 데이터가 더 엄격한 일관성을 요구하는지 나눔 |

```text
+-------------+      +------------------+
| 분할 장애 발생  | ---> | 가용성/일관성 판단 |
+-------------+      +------------------+
        |
        v
+-------------+      +------------------+
| 정상 운영 상태  | ---> | 속도/일관성 판단  |
+-------------+      +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 업무 성격 구분   | --> | 분할 시 정책 정함 | --> | 평상시 지연 목표 정함 | --> | 실제 운영값 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **업무 성격 구분**: 틀리면 안 되는 데이터인지, 빠르면 되는 데이터인지 나눔
2. **분할 시 정책 정함**: 장애 때 일관성과 가용성 중 무엇을 우선할지 정함
3. **평상시 지연 목표 정함**: 복제 동기화 수준과 응답 목표를 정함
4. **실제 운영값 검증**: 지연 시간과 불일치 정도가 목표 안에 들어오는지 확인함

## Ⅵ. 실무 적용 및 유의점

1. 글로벌 주문 데이터처럼 지역이 달라도 같은 값이 중요하면 동기 복제 범위를 좁혀서라도 정합성을 우선하고 쓰기 지연 시간과 데이터 충돌 건수로 운영 수준을 확인함
2. 사용자 피드처럼 빠른 응답이 더 중요한 영역은 비동기 복제를 쓰되 오래된 값이 허용되는 시간을 먼저 정하고 응답 지연과 데이터 지연 시간을 함께 점검함

## Ⅶ. 결론

PACELC의 핵심은 장애 때의 선택만이 아니라 평상시에도 속도와 일관성 비용을 함께 계산해 저장소 구조를 정하는 데 있음.
