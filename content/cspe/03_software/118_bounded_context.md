## Ⅰ. 개요
- 정의: Bounded Context의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Order Context] <-- Context Map --> [Payment Context]
     (Order ID)                         (Transaction)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 바운디드 컨텍스트 | 모델이 적용되는 논리적 경계 영역 | 행정 구역 |
| 유비쿼터스 언어 | 전 영역에서 동일하게 사용되는 공통어 | 표준어 |
| 컨텍스트 맵 | 각 컨텍스트 간의 관계를 시각화한 도면 | 세계 지도 |

> 요약: 용어의 의미가 명확하게 유지되는 경계와 공통 언어 체계임.

## Ⅲ. 절차
- ASCII 흐름도
  Domain Analysis -> Identify Contexts -> Define Language -> Map Rel.

1. 도메인 분할: 거대 도메인을 독립적인 하위 도메인으로 분리함.
2. 경계 설정: 용어의 중의성을 제거할 수 있는 경계(BC) 정의함.
3. 언어 정의: 해당 경계 내에서 통용되는 용어 사전 구축함.
4. 인터페이스 정의: 컨텍스트 간 데이터 교환 방식(ACL 등) 수립함.

> 요약: 컨텍스트 분리를 통해 대규모 시스템의 복잡성 통제함.

## Ⅳ. 문제점
- 컨텍스트 간 경계 모호 시 중복 개발 및 데이터 불일치 발생함.
- 유비쿼터스 언어 유지 관리 부재 시 다시 용어 혼선 발생함.

## Ⅴ. 개선방안
- 명확한 인터페이스 설계와 부패 방지 계층(ACL) 활용함.
- 코드와 용어 사전의 동기화를 위한 자동화된 문서화 도구 활용함.

## Ⅵ. 전망
- MSA 환경에서 서비스 경계 도출의 핵심 논리적 근거로 활용됨.
- CSF: 조직 구조(Conway's Law)와 바운디드 컨텍스트의 정렬임.
