## 미리 알고가기

- 애그리게이트(Aggregate): 데이터의 생명주기를 같이 하며 도메인의 트랜잭션 일관성을 유지해야 하는 엔티티와 값 객체(Value Object)의 묶음임
- 애그리게이트 루트(Aggregate Root): 외부에서 애그리게이트 내부 객체에 접근할 때 반드시 거쳐야 하는 유일한 진입점 엔티티임
- 이벤트 스토밍(Event Storming): 도메인 전문가와 개발자가 포스트잇을 사용하여 도메인 이벤트 중심으로 비즈니스 워크플로우를 탐색하는 시각적 워크숍 기법임
- 도메인 이벤트(Domain Event): 비즈니스 영역에서 과거에 이미 발생한 의미 있는 사실이나 상태 변화를 의미함
- 명령(Command): 도메인 이벤트를 유발하는 트리거 역할을 수행하며, 시스템의 상태 변경을 요구하는 행위임

## 작성 근거(검토용)

- 애그리게이트와 이벤트 스토밍은 역할, 산출물, 활용 시점, 경계 오류를 핵심 비교축으로 선정함
- 구성과 절차는 이벤트 흐름에서 일관성 경계를 도출하는 과정을 중심으로 제시함
- 실무 판단은 용어 불일치 건수, 경계 밖 변경률, 트랜잭션 경합률로 구체화함
- 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정함

## Ⅰ. 개요

- **정의/개념**: 애그리게이트는 함께 일관성을 유지할 엔티티의 경계이며, 이벤트 스토밍은 이벤트 흐름에서 명령·정책·경계를 찾는 협업 기법임
- **배경/필요성**: 복잡한 도메인에서 함께 변경할 범위와 모델 경계를 찾기 위해 업무 사건의 흐름을 시각화할 필요가 있음

### 쉽게 이해하기 (학습용)
- 장난감을 만들 때 부품들을 한 상자(애그리게이트)에 모으고, 포스트잇으로 장난감 조립 순서(이벤트 스토밍)를 벽에 붙여 맞춰보는 작업임

## Ⅱ. 특징

- 애그리게이트는 일관성 범위를 제한해 트랜잭션 폭을 줄임
- 이벤트 스토밍은 도메인 전문가와 개발자가 이벤트 흐름을 함께 작성해 업무 의미를 합의하게 함
- 애그리게이트 경계가 넓으면 트랜잭션 경합이 늘고, 좁으면 하나의 불변 규칙이 여러 경계로 흩어짐
- 이벤트 스토밍 결과의 이벤트·명령·정책·경계 후보를 애그리게이트와 코드 책임으로 구체화해야 함

### 쉽게 이해하기 (학습용)
- 같이 움직여야 하는 데이터끼리 묶어 데이터가 깨지는 것을 막고, 포스트잇 워크숍을 통해 모든 팀원이 업무 흐름을 한눈에 보게 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 애그리게이트 | 이벤트 스토밍 |
|:---|:---|:---|
| 핵심 역할 및 목적 | 도메인 모델의 일관성 경계를 정의함 | 도메인 흐름과 경계 후보를 탐색함 |
| 산출 결과물 및 상태 | 불변 규칙과 트랜잭션 일관성 경계 | 이벤트·명령·정책의 시간 흐름과 경계 후보 |
| 주요 한계 및 오용 리스크 | 경계를 넓게 잡을 시 트랜잭션 경합 발생 | 워크숍 결과가 코드 설계에 유기적으로 연동되지 못함 |

> 요약: 이벤트 스토밍은 업무 흐름에서 경계 후보를 찾고, 애그리게이트는 불변 규칙의 일관성 경계를 확정함.

### 쉽게 이해하기 (학습용)
- 애그리게이트는 데이터의 무결성을 지키는 울타리 역할을 하고, 이벤트 스토밍은 그 울타리를 어디에 쳐야 할지 지도(포스트잇)를 그리는 역할임

## Ⅳ. 설계 요소 및 구조

```text
[주문 애그리게이트 (일관성 경계)]
  └─ [주문 루트 엔티티 (Aggregate Root)] <── 외부 접근 진입점
       ├─ [주문 항목 엔티티 (Entity)]
       └─ [배송지 주소 객체 (Value Object)]
```

| 설계 요소 | 설명 |
|:---|:---|
| 애그리게이트 루트 | 외부 요청의 진입점으로 내부 엔티티의 상태 변경을 통제함 |
| 일관성 경계 | 하나의 트랜잭션에서 불변 규칙을 보장할 범위를 정함 |
| 도메인 이벤트 흐름 | 사건을 시간 순서로 배치해 업무 흐름과 경계 후보를 드러냄 |
| 명령·정책 연결 | 이벤트의 원인인 명령과 후속 처리 정책을 연결함 |

> 요약: 이벤트·명령·정책의 흐름에서 일관성 경계를 찾고 애그리게이트 루트가 내부 변경을 통제함.

### 쉽게 이해하기 (학습용)
- 울타리 입구의 대장(루트), 그 안의 식솔들(엔티티, 밸류)이 있고, 이들이 겪는 사건(이벤트)과 행동(명령)이 엮여 있는 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 나열      | --> | 명령/정책 연결 | --> | 경계 후보 식별  | --> | 애그리게이트 설계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **이벤트 나열**: 도메인에서 발생하는 핵심 이벤트를 시간순으로 배치함
2. **명령 및 정책 연결**: 이벤트를 일으키는 명령과 후속 규칙을 붙임
3. **경계 후보 식별**: 같은 불변 규칙과 데이터가 반복되는 흐름 단위를 찾음
4. **애그리게이트 설계**: 일관성 규칙과 트랜잭션 경계를 모델에 반영함

> 요약: 이벤트 흐름에 명령과 정책을 연결해 경계 후보를 찾고 불변 규칙 단위로 애그리게이트를 설계함.

### 쉽게 이해하기 (학습용)
- 먼저 과거형 포스트잇(이벤트)을 붙이고, 그것을 일으킨 행동(명령)을 쓴 뒤, 관련된 개념들을 묶어 하나의 울타리(애그리게이트)로 만드는 흐름임

## Ⅵ. 실무 사례

- 이커머스 플랫폼 구축 시, 주문 서비스 영역에서 도메인 전문가와 개발자가 이벤트 스토밍 워크숍을 통해 업무 사건을 나열하고, 주문서와 결제 정보의 일관성을 보장하기 위해 각각의 애그리게이트로 격리하여 조치함.

### 쉽게 이해하기 (학습용)
- 쇼핑몰에서 결제가 완료되면(이벤트) 결제 내역과 주문 내역이 하나의 울타리(애그리게이트)로 함께 묶여 처리되도록 구현한 사례임

## Ⅶ. 결론

- 이벤트 스토밍은 복잡한 비즈니스 요구사항을 빠르게 시각화하며, 애그리게이트는 이를 데이터 무결성을 유지하는 코드 경계로 안착시킴.
- 대규모 트랜잭션 환경에서 애그리게이트 범위가 너무 넓으면 성능 지연이 발생하므로 비동기 도메인 이벤트 발행을 통한 결과적 일관성 설계를 적극 활용해야 함.

### 쉽게 이해하기 (학습용)
- 업무를 빠르게 시각화하고 코드의 일정한 경계를 잡아주지만, 한 번에 처리하려는 영역이 너무 크면 렉(병목)이 생기므로 주의해서 나누어야 함
