## 미리 알고가기

- 애그리게이트는 일관성 경계를 가지는 도메인 모델 단위임
- 이벤트 스토밍은 도메인 이벤트를 중심으로 비즈니스 흐름을 탐색하는 워크숍 기법임
- 둘은 DDD 실무에서 경계와 규칙을 찾는 데 함께 쓰인다

## Ⅰ. 개요

- **정의/개념**: 애그리게이트는 하나의 트랜잭션과 일관성 경계 안에서 함께 관리되어야 하는 엔티티 묶음이고, 이벤트 스토밍은 도메인 이벤트를 순서대로 배치해 비즈니스 흐름과 명령과 정책과 경계를 탐색하는 협업 기법임
- **배경/필요성**: 복잡한 도메인에서는 무엇을 함께 변경해야 하는지와 어디서 경계를 잘라야 하는지 파악하기 어렵기 때문에, 모델 경계와 이벤트 흐름을 동시에 시각화하는 방법이 필요함

## Ⅱ. 특징

- 애그리게이트는 일관성 범위를 제한해 트랜잭션 폭을 줄임
- 이벤트 스토밍은 도메인 전문가와 개발자가 같은 보드 위에서 의미를 맞출 수 있게 함
- 애그리게이트를 너무 크게 잡으면 성능과 결합이 나빠지고 너무 작게 잡으면 정합성 규칙이 흩어짐
- 이벤트 스토밍은 빠른 탐색에 강하지만 결과를 구조로 정리하는 후속 작업이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 애그리게이트 | 이벤트 스토밍 |
|:---|:---|:---|
| 역할 | 도메인 모델의 일관성 경계 | 도메인 탐색과 흐름 발견 기법 |
| 장점 | 트랜잭션 범위 명확화 | 협업과 용어 정렬 빠름 |
| 한계 | 경계 설정 어려움 | 산출물 구조화 필요 |
| 활용 시점 | 모델 설계 단계 | 요구 탐색과 경계 탐색 단계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Aggregate Root | 외부가 접근하는 유일한 진입점이 되어 내부 상태 무결성을 통제함 |
| Consistency Boundary | 함께 변경되어야 하는 규칙 범위를 정해 트랜잭션 크기와 성능을 좌우함 |
| Domain Event Timeline | 사건 순서를 따라 비즈니스 흐름과 경계 후보를 빠르게 드러냄 |
| Command and Policy Link | 무엇이 이벤트를 일으키고 어떤 후속 규칙이 따르는지 연결해 모델 의미를 구체화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 나열      | --> | 명령/정책 연결 | --> | 경계 후보 식별  | --> | 애그리게이트 설계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **이벤트 나열**: 도메인에서 발생하는 핵심 이벤트를 시간순으로 배치함
2. **명령과 정책 연결**: 이벤트를 발생시키는 명령과 후속 규칙을 붙임
3. **경계 후보 식별**: 의미가 강하게 묶이는 흐름 단위를 찾음
4. **애그리게이트 설계**: 일관성 규칙과 트랜잭션 경계를 모델에 반영함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 애그리게이트 경계를 너무 크게 잡으면 락 범위와 변경 영향이 커져 성능과 유연성이 떨어질 수 있음
   - 해결방안: invariants 중심으로 경계를 축소하고 aggregate size score와 transaction contention rate로 검증함
2. 문제: 이벤트 스토밍 결과를 코드 구조로 연결하지 않으면 워크숍은 했지만 설계 정렬이 남지 않을 수 있음
   - 해결방안: 후속 모델 정리 세션을 운영하고 workshop-to-model conversion rate와 terminology alignment score로 검증함
3. 문제: 도메인 전문가 참여가 약하면 이벤트 흐름이 기술 관점으로 왜곡되어 핵심 규칙을 놓칠 수 있음
   - 해결방안: 현업 참여율을 높이고 domain participation rate와 missed rule discovery count로 검증함

## Ⅶ. 적용 사례

- 주문 도메인 설계에서는 이벤트 스토밍을 수행하고, workshop-to-model conversion rate와 terminology alignment score로 결과를 확인함
- 결제 승인 모델에서는 애그리게이트 경계를 조정하고, transaction contention rate와 aggregate size score로 결과를 확인함
- 현업 참여형 설계 워크숍에서는 비즈니스 담당자를 포함하고, domain participation rate와 missed rule discovery count로 결과를 확인함

## Ⅷ. 결론

애그리게이트와 이벤트 스토밍의 핵심은 도메인 규칙을 많이 적는 데 있지 않고 어디까지를 함께 일관되게 바꿔야 하는지 명확히 찾는 데 있음.
