## 미리 알고가기

- 애그리게이트는 하나의 일관성 경계 안에서 함께 관리할 엔티티 묶음임
- 애그리게이트 루트는 외부가 해당 경계에 접근하는 유일한 진입점임
- 이벤트 스토밍은 도메인 이벤트를 시간 순서로 놓고 업무 흐름을 탐색하는 워크숍 기법임

## 작성 근거(검토용)

- 애그리게이트와 이벤트 스토밍은 역할, 산출물, 활용 시점, 경계 오류를 핵심 비교축으로 선정함
- 구성과 절차는 이벤트 흐름에서 일관성 경계를 도출하는 과정을 중심으로 제시함
- 실무 판단은 용어 불일치 건수, 경계 밖 변경률, 트랜잭션 경합률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 애그리게이트는 함께 일관성을 유지할 엔티티의 경계이며, 이벤트 스토밍은 이벤트 흐름에서 명령·정책·경계를 찾는 협업 기법임
- **배경/필요성**: 복잡한 도메인에서 함께 변경할 범위와 모델 경계를 찾기 위해 업무 사건의 흐름을 시각화할 필요가 있음

## Ⅱ. 특징

- 애그리게이트는 일관성 범위를 제한해 트랜잭션 폭을 줄임
- 이벤트 스토밍은 도메인 전문가와 개발자가 이벤트 흐름을 함께 작성해 업무 의미를 합의하게 함
- 애그리게이트 경계가 넓으면 트랜잭션 경합이 늘고, 좁으면 하나의 불변 규칙이 여러 경계로 흩어짐
- 이벤트 스토밍 결과의 이벤트·명령·정책·경계 후보를 애그리게이트와 코드 책임으로 구체화해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 애그리게이트 | 이벤트 스토밍 |
|:---|:---|:---|
| 주된 역할 | 도메인 모델의 일관성 경계를 정의함 | 도메인 흐름과 경계 후보를 탐색함 |
| 산출 결과 | 불변 규칙과 트랜잭션 일관성 경계 | 이벤트·명령·정책의 시간 흐름과 경계 후보 |
| 주된 한계 | 경계를 잘못 잡으면 성능과 일관성이 함께 흔들림 | 워크숍 결과를 모델·코드 경계에 반영하지 못할 수 있음 |
| 활용 시점 | 모델 설계에서 불변 규칙·트랜잭션 범위 확정 | 요구 탐색에서 업무 흐름·경계 후보 도출 |

> 요약: 이벤트 스토밍은 업무 흐름에서 경계 후보를 찾고, 애그리게이트는 불변 규칙의 일관성 경계를 확정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 애그리게이트 루트 | 외부 요청의 진입점으로 내부 엔티티의 상태 변경을 통제함 |
| 일관성 경계 | 하나의 트랜잭션에서 불변 규칙을 보장할 범위를 정함 |
| 도메인 이벤트 흐름 | 사건을 시간 순서로 배치해 업무 흐름과 경계 후보를 드러냄 |
| 명령·정책 연결 | 이벤트의 원인인 명령과 후속 처리 정책을 연결함 |

> 요약: 이벤트·명령·정책의 흐름에서 일관성 경계를 찾고 애그리게이트 루트가 내부 변경을 통제함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 나열      | --> | 명령/정책 연결 | --> | 경계 후보 식별  | --> | 애그리게이트 설계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **이벤트 나열**: 도메인에서 발생하는 핵심 이벤트를 시간순으로 배치함
2. **명령 및 정책 연결**: 이벤트를 일으키는 명령과 후속 규칙을 붙임
3. **경계 후보 식별**: 같은 불변 규칙과 데이터가 반복되는 흐름 단위를 찾음
4. **애그리게이트 설계**: 일관성 규칙과 트랜잭션 경계를 모델에 반영함

> 요약: 이벤트 흐름에 명령과 정책을 연결해 경계 후보를 찾고 불변 규칙 단위로 애그리게이트를 설계함.

## Ⅵ. 실무 사례

1. 주문·결제 도메인은 이벤트 스토밍으로 경계를 찾고 용어 불일치·경계 밖 변경률을 확인함
2. 승인·정산 모델은 불변 규칙으로 애그리게이트를 나누고 트랜잭션 경합률을 확인함

## Ⅶ. 결론

이벤트 스토밍으로 업무 흐름을 탐색하고 애그리게이트로 함께 일관성을 유지할 모델 범위를 확정함
