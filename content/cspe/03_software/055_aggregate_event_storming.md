## 미리 알고가기

- 애그리게이트는 하나의 일관성 경계 안에서 함께 관리할 엔티티 묶음임
- 애그리게이트 루트는 외부가 해당 경계에 접근하는 유일한 진입점임
- 이벤트 스토밍은 도메인 이벤트를 시간 순서로 놓고 업무 흐름을 탐색하는 워크숍 기법임

## Ⅰ. 개요

- **정의/개념**: 애그리게이트는 하나의 트랜잭션과 일관성 경계 안에서 함께 관리해야 하는 엔티티 묶음이고, 이벤트 스토밍은 도메인 이벤트를 순서대로 배치해 비즈니스 흐름과 명령과 정책과 경계를 탐색하는 협업 기법임.
- **배경/필요성**: 복잡한 도메인에서는 무엇을 함께 바꿔야 하는지와 어디서 경계를 잘라야 하는지 파악하기 어려우므로, 모델 경계와 이벤트 흐름을 함께 시각화하는 방법이 필요함.

## Ⅱ. 특징

- 애그리게이트는 일관성 범위를 제한해 트랜잭션 폭을 줄임
- 이벤트 스토밍은 도메인 전문가와 개발자가 같은 보드 위에서 의미를 맞추게 함
- 애그리게이트를 너무 크게 잡으면 성능과 결합이 나빠지고 너무 작게 잡으면 규칙이 흩어짐
- 이벤트 스토밍 결과의 이벤트·명령·정책·경계 후보를 aggregate와 코드 책임으로 구체화해야 함

## Ⅲ. 종류 및 비교

| 구분 | 애그리게이트 | 이벤트 스토밍 |
|:---|:---|:---|
| 주된 역할 | 도메인 모델의 일관성 경계를 정의함 | 도메인 흐름과 경계 후보를 탐색함 |
| 산출 결과 | 불변 규칙과 트랜잭션 일관성 경계 | 이벤트·명령·정책의 시간 흐름과 경계 후보 |
| 주된 한계 | 경계를 잘못 잡으면 성능과 정합성이 함께 흔들림 | 워크숍 결과를 코드 구조로 옮기지 않으면 효과가 남지 않음 |
| 활용 시점 | 모델 설계에서 불변 규칙·트랜잭션 범위 확정 | 요구 탐색에서 업무 흐름·경계 후보 도출 |

> 요약: 이벤트 스토밍은 경계를 찾는 도구이고 애그리게이트는 찾은 경계를 모델로 굳히는 도구임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Aggregate Root | 외부가 접근하는 유일한 진입점이 되어 내부 상태 무결성을 통제함 |
| Consistency Boundary | 함께 변경되어야 하는 규칙 범위를 정해 트랜잭션 크기와 성능을 좌우함 |
| Domain Event Timeline | 사건 순서를 따라 비즈니스 흐름과 경계 후보를 빠르게 드러냄 |
| Command and Policy Link | 무엇이 이벤트를 일으키고 어떤 후속 규칙이 따르는지 연결해 모델 의미를 구체화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 나열      | --> | 명령/정책 연결 | --> | 경계 후보 식별  | --> | 애그리게이트 설계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **이벤트 나열**: 도메인에서 발생하는 핵심 이벤트를 시간순으로 배치함
2. **명령 및 정책 연결**: 이벤트를 일으키는 명령과 후속 규칙을 붙임
3. **경계 후보 식별**: 의미가 강하게 묶이는 흐름 단위를 찾음
4. **애그리게이트 설계**: 일관성 규칙과 트랜잭션 경계를 모델에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 주문·결제 같은 핵심 도메인 설계에서는 이벤트 스토밍으로 경계 후보를 찾되 워크숍 결과가 코드 구조로 이어지지 않으면 의미가 없으므로 후속 모델 정리 세션을 함께 운영하고 워크숍 결과 반영률과 용어 불일치 건수로 확인함
2. 승인·정산 모델처럼 규칙이 많은 영역에서는 애그리게이트 경계를 너무 크게 잡기 쉬우므로 불변 규칙 기준으로 범위를 축소하고 애그리게이트 크기와 트랜잭션 경합 비율로 확인함

## Ⅶ. 결론

애그리게이트와 이벤트 스토밍의 핵심은 도메인 규칙을 많이 적는 데 있지 않고 어디까지를 함께 일관되게 바꿔야 하는지 찾는 데 있음.
