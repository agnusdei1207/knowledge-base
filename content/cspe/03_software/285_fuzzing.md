## Ⅰ. 개요
- **정의**: 무작위·변형 입력을 자동 생성하여 프로그램 결함을 탐지하는 동적 테스트 기법
- **배경/필요성**: 수동 테스트로 예측 불가한 경계값·이상 입력 조합 탐색이 필요함
- **비유**: 자판기에 온갖 이물질을 넣어보며 오작동을 유발하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 테스트 자동화·보안 취약점 탐지 | 생성 기반 vs 변이 기반 구분 | 커버리지 가이드 퍼징 개념 포함 필요 |

> 요약: 무작위·변형 입력 자동 주입으로 예측 불가 결함을 탐지하는 동적 기법임

## Ⅱ. 구성요소
```text
Seed Corpus --> Mutator --> Target Program --> Crash Monitor
                  ^                               |
                  +--- Coverage Feedback ----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 시드 코퍼스 | 초기 유효 입력 집합, 변이의 출발점 | 원본 레시피 모음 |
| 변이기(Mutator) | 비트 플립·삽입·삭제 등으로 입력 변형 생성 | 레시피 재료를 무작위 변경 |
| 크래시 모니터 | 비정상 종료·메모리 오류·타임아웃 감지 | 요리 결과 이상 여부 판정 |
| 커버리지 피드백 | 새 경로 도달 시 해당 입력을 코퍼스에 추가 | 새 구역 발견 시 탐험 지도 갱신 |

> 요약: 시드→변이→실행→피드백의 순환 루프로 탐색 범위를 확장하는 구조임

## Ⅲ. 절차
```text
시드 준비 --> 입력 변이 --> 대상 실행 --> 결과 분류
                 ^                          |
                 +---- 피드백 루프 ---------+
```
- 1단계: 유효 입력 샘플을 시드 코퍼스로 수집·구성
- 2단계: 변이 전략(비트 플립·사전 기반·문법 기반) 적용하여 입력 생성
- 3단계: 대상 프로그램에 변이 입력 주입 후 실행 상태 모니터링
- 4단계: 크래시 입력 저장·중복 제거·근본 원인 분석 수행

> 요약: 시드→변이→실행→분류를 반복 순환하며 결함 탐지 범위를 확장함

## Ⅳ. 문제점
- 상태 폭발: 입력 공간이 방대하여 탐색 수렴에 장시간 소요 — 자원 소모 과다
- 깊은 경로 미도달: 복잡한 조건 분기 통과 어려움 — 핵심 로직 결함 미탐지
- 크래시 분류 난이: 동일 근본 원인의 중복 크래시 대량 발생 — 분석 효율 저하

> 요약: 상태 폭발·깊은 경로 미도달·크래시 중복이 주요 한계임

## Ⅴ. 개선방안
1. 단기: 커버리지 가이드 퍼징(AFL, libFuzzer) 적용으로 탐색 수렴 가속
2. 중기: 심볼릭 실행과 결합(Hybrid Fuzzing)하여 깊은 분기 조건 해결
3. 장기: 자동 크래시 군집화·근본 원인 자동 분류 도구 도입

> 요약: 커버리지 가이드·하이브리드 퍼징·자동 분류로 탐지 효율 향상 필요

## Ⅵ. 전망
- 발전 방향: AI 기반 입력 생성으로 문법 인식 퍼징 정밀도 향상
- 기술사적 판단: OSS-Fuzz 등 대규모 연속 퍼징 인프라가 산업 표준화 중임
- 기술사 제언: CI 파이프라인에 퍼징 게이트 통합으로 보안 결함 사전 차단 체계 수립 필요
