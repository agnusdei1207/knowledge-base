## 미리 알고가기

- 격리 수준(Isolation Level): 동시에 실행되는 트랜잭션이 서로의 변경 내용을 어디까지 볼 수 있는지 정의하는 기준임
- 동시성 제어(Concurrency Control): 다중 트랜잭션이 데이터베이스에 동시에 접근할 때 일관성을 보장하기 위한 기술임
- 직렬화(Serialization): 트랜잭션을 순차적으로 실행한 것과 동일한 결과를 보장하는 상태임
- 일관성 오류(Read Anomalies): 동시 실행 트랜잭션 간 격리성 부족으로 인해 조회 결과가 불일치하는 현상임
- MVCC(Multi-Version Concurrency Control): 데이터의 다중 버전을 유지하여 잠금 없이 동시 조회를 지원하는 방식임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 동시성 제어의 핵심 기준인 4단계 격리 수준(Read Uncommitted, Read Committed, Repeatable Read, Serializable)을 통해 일관성과 성능 간의 트레이드오프를 규명하기 위함
- 절 구성 및 전개 흐름 이유: 개요에서 격리 수준의 필요성을 정의한 후, 각 수준별 특징을 분류함. 비교표에서 SQL 표준 4단계의 차이를 분석하고, 구조에서는 읽기 가시성과 MVCC 제어 방식을 도식화함. 절차에서는 트랜잭션 격리 수준 적용 흐름을 보이고, 실무 사례와 결론으로 트레이드오프 조절 방안을 제언함
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 본문, 표 헤더·셀, 요약, 결론의 맞춤법과 한국어 조사 결합, 어색한 복합명사를 확인하고 5회 완독 검수를 완료함

## Ⅰ. 개요

- **정의/개념**: 트랜잭션 격리 수준은 동시 트랜잭션의 변경 가시성과 허용할 읽기 이상 현상을 단계별로 정의한 동시성 제어의 성능·일관성 절충 기준임
- **배경/필요성**: 다중 사용자 데이터베이스에서 트랜잭션의 일관성을 유지하면서도 잠금 경합으로 인한 지연을 최소화하기 위해 업무 성격에 맞는 최적의 격리 수준 선택이 필요함

### 쉽게 이해하기 (학습용)
- 격리 수준은 여러 사람이 한 장의 장부를 동시에 고칠 때, 다른 사람의 행동이 내 눈에 보이지 않도록 벽(격리막)의 높이를 단계별로 설정하는 것에 비유할 수 있음

## Ⅱ. 특징

- 허용할 일관성 오류 범위를 기준으로 총 4단계 수준으로 구분함
- 동일 수준이라도 데이터베이스 아키텍처(2PL 잠금 방식 또는 MVCC 버전 관리)에 따라 실제 비차단 동작 범위가 상이함
- 수준이 격상될수록 정합성은 보장되나 잠금 대기 지연 및 직렬화 재시도에 따른 시스템 자원 경합이 증가함
- 격리 수준은 데이터베이스 옵션이 아니라 업무별 위험 허용 범위를 정하는 설계 결정임

### 쉽게 이해하기 (학습용)
- 벽이 낮으면 옆 사람의 미완성 작업을 쉽게 보지만 장부가 엉망이 되고, 벽이 너무 높으면 옆 사람이 끝낼 때까지 대기해야 해서 속도가 매우 느려짐

## Ⅲ. 종류 및 비교

| 판단 기준 | Read Uncommitted | Read Committed | Repeatable Read | Serializable |
|:---|:---|:---|:---|:---|
| 읽기 가시성 | 커밋되지 않은 데이터 참조 | 커밋이 완료된 데이터만 참조 | 트랜잭션 시작 시점의 스냅샷 참조 | 직렬 실행과 동일한 정적 상태 참조 |
| 방지하는 이상 현상 | 이상 현상을 방지하지 못함 | Dirty Read 방지 | Dirty Read, Non-Repeatable Read 방지 | Dirty Read, Non-Repeatable Read, Phantom Read 방지 |
| 실무 경합 비용 | 잠금 및 버전 관리가 없어 경합 없음 | 커밋된 버전 관리 및 단기 공유 잠금 | 다중 버전 유지보수 및 범위 잠금 대기 | 인덱스 범위 잠금 및 직렬화 실패 재시도 |

> 요약: 격리 수준이 높아질수록 Dirty·Non-Repeatable·Phantom Read를 추가로 방지하고 경합 비용이 증가할 수 있음.

### 쉽게 이해하기 (학습용)
- 4단계 수준은 남이 낙서 중인 노트를 보는 것(1단계)부터, 다 쓴 페이지만 보는 것(2단계), 내가 보고 있는 페이지가 안 변하는 것(3단계), 아예 독점해서 순서대로 보는 것(4단계)으로 비교됨

## Ⅳ. 설계 요소 및 구조

```text
+-----------------------------------------------------------+
|                  트랜잭션 격리 수준 통제                  |
+-----------------------------------------------------------+
        |                          |
        v                          v
+-------------------+      +-------------------+
|  1. 읽기 가시성   |      |  2. 제어 메커니즘 |
|  - Undo 스냅샷    |      |  - 공유/배타 잠금 |
|  - Read View 정의 |      |  - 인덱스 범위 락 |
+-------------------+      +-------------------+
        |                          |
        +------------+-------------+
                     v
+----------------------------------------------+
|             3. 충돌 처리 및 업무 매핑        |
|  - 직렬화 실패 처리 (대기 / 롤백 후 재시도)  |
|  - 서비스 일관성 목표 (금융: 4단계, 일반: 2단계)|
+----------------------------------------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 읽기 가시성 규칙 | 트랜잭션이 타 트랜잭션의 변경 데이터를 조회할 수 있는 한계를 지배하는 읽기 뷰 규칙 |
| 잠금 및 버전 제어 | 격리 수준을 보장하기 위해 사용되는 비관적 잠금 및 MVCC 다중 버전 관리 엔진 |
| 충돌 처리 정책 | 직렬화 실패나 데드락 감지 시 트랜잭션을 대기시키거나 롤백 및 재시도를 처리하는 규칙 |
| 업무 매핑 기준 | 금융 거래, 통계 분석 등 서비스 요건에 맞게 시스템 격리 성능과 일관성 수준을 조율하는 가이드 |

> 요약: 읽기 가시성은 잠금·MVCC가 구현하고 충돌 정책과 업무 위험이 격리 수준 선택을 결정함.

### 쉽게 이해하기 (학습용)
- 이 구조는 독서 뷰(누가 언제 쓴 글까지 볼 것인가)와 접근 잠금(누구한테 자물쇠를 채울 것인가)을 통해 시스템 안정을 통제하는 뼈대임

## Ⅴ. 원리 및 절차 흐름도

```text
[트랜잭션 시작] 
      │
      ▼
[격리 수준 조회] ── (설정된 4단계 격리 수준 확인)
      │
      ▼
[스냅샷/잠금 획득] ── (Read View 생성 또는 대상 데이터 행에 잠금 설정)
      │
      ▼
[데이터 연산 수행] ── (일관성 이상 현상 방지 규칙 하에 읽기/쓰기 처리)
      │
      ▼
[커밋 및 자원 반환] ── (변경사항 영구 반영 및 잠금 해제/버전 정리 유도)
```

1. **트랜잭션 시작**: 클라이언트 요청으로 트랜잭션이 구동되며 고유 식별자가 할당됨
2. **격리 수준 조회**: 설정 파일이나 쿼리 옵션에 명시된 4단계 격리 수준 정책을 확인하여 규칙을 적용함
3. **스냅샷/잠금 획득**: 수준이 Read Committed/Repeatable Read이면 스냅샷을 구성하고, Serializable이면 읽기 범위 잠금을 확보함
4. **데이터 연산 수행**: 이상 현상이 방지되는 통제 하에서 조회 및 갱신 연산을 수행함
5. **커밋 및 자원 반환**: 작업을 완료하여 디스크에 반영하고 획득했던 락을 반환하며 스냅샷 정리를 준비함

### 쉽게 이해하기 (학습용)
- 작업자가 일감을 시작하기 전 장부 격리 규칙을 정한 뒤, 그 규칙대로 자물쇠를 걸거나 옛날 복사본을 받아 일하고, 끝나면 장부를 덮는 흐름임

## Ⅵ. 실무 사례

1. 재고 차감 DB는 Serializable과 재시도를 적용하고 직렬화 실패율·재고 불일치 건수를 확인함
2. 목록 조회 DB는 Read Committed를 적용하고 재조회 불일치 건수·p95 응답 시간을 확인함

### 쉽게 이해하기 (학습용)
- 돈이 오가는 이체는 100% 정합성을 위해 꼼꼼히 확인하고(4단계), 상품 목록 검색은 조금 어긋나도 되므로 빠른 속도를 택함(2단계)

## Ⅶ. 결론

- 트랜잭션 격리 수준은 일관성과 동시 처리 성능 간의 트레이드오프를 결정하는 핵심 파라미터로서, 서비스 정합성 요구 규격에 맞춰 정교하게 매핑되어야 함
- 궁극적으로는 기본 수준인 Read Committed 하에서 비관적/낙관적 잠금을 결합하거나, 고부하 환경에서는 CQRS 패턴을 통해 읽기와 쓰기 데이터베이스를 격리하는 아키텍처적 보완이 요구됨

### 쉽게 이해하기 (학습용)
- 격리 수준은 성능과 데이터 정합성의 균형을 잡는 저울이며, 필요할 경우 분리된 조회용 복제 데이터베이스를 두어 부하를 극복해야 함
