## 미리 알고가기

- 격리 수준은 동시에 실행되는 트랜잭션이 서로의 변경을 어디까지 볼 수 있는지 정하는 기준임
- Dirty Read는 커밋되지 않은 값을 읽는 문제이고, Non-Repeatable Read는 같은 행을 다시 읽었을 때 값이 달라지는 문제이며, Phantom Read는 같은 조건으로 다시 조회했을 때 행 집합이 달라지는 문제임
- 수준이 높아질수록 이상 현상은 줄지만 잠금 대기와 재시도 비용은 커질 수 있음

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 격리 수준은 읽기 가시성, 방지하는 이상 현상, 경합 비용, 적합 업무를 핵심 축으로 설명함
- 비교표는 SQL 표준 4단계가 허용·방지하는 읽기 이상과 적용 조건을 대비함
- 재고 차감과 목록 조회 DB는 직렬화 실패율·재조회 불일치 건수로 검증함

## Ⅰ. 개요

- **정의/개념**: 트랜잭션 격리 수준은 동시 트랜잭션의 변경 가시성과 허용할 읽기 이상 현상을 단계별로 정하는 동시성 제어 기준임
- **배경/필요성**: 업무 일관성과 잠금·버전 경합 비용을 함께 통제하기 위해 허용하지 않을 이상 현상별 격리 수준을 선택해야 함

## Ⅱ. 특징

- 허용할 읽기 이상 현상 범위를 기준으로 수준을 나눔
- 같은 이름의 수준이라도 데이터베이스 제품의 잠금 방식과 MVCC 구현에 따라 세부 동작이 달라질 수 있음
- 수준이 높아지면 방지하는 이상 현상이 늘고 잠금 대기·직렬화 재시도도 증가할 수 있음
- 격리 수준은 데이터베이스 옵션이 아니라 업무별 위험 허용 범위를 정하는 설계 결정임

## Ⅲ. 종류 및 비교

| 판단 기준 | Read Uncommitted | Read Committed | Repeatable Read | Serializable |
|:---|:---|:---|:---|:---|
| 읽기 보장 수준 | 커밋 전 값도 볼 수 있음 | 커밋된 값만 읽음 | 같은 행을 다시 읽으면 값이 유지됨 | 동시 실행 결과가 직렬 실행과 같게 맞춰짐 |
| 방지하는 이상 현상 | SQL 표준의 세 읽기 이상을 허용함 | Dirty Read를 방지함 | Dirty Read와 Non-Repeatable Read를 방지함 | 세 읽기 이상을 모두 방지함 |
| 경합 영향 | 읽기 제약이 가장 적음 | 미커밋 변경 읽기를 차단함 | 반복 읽기 보장으로 버전·잠금 유지가 늘 수 있음 | 충돌 시 대기·재시도 가능성이 가장 큼 |
| 대표 업무 | 중간 상태 허용 시험·특수 분석 | 일반 조회·온라인 트랜잭션 | 반복 조회 일관성이 필요한 업무 | 직렬 실행과 같은 결과가 필요한 핵심 거래 |

> 요약: 격리 수준이 높아질수록 Dirty·Non-Repeatable·Phantom Read를 추가로 방지하고 경합 비용이 증가할 수 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 읽기 가시성 규칙 | 현재 트랜잭션이 다른 트랜잭션의 변경을 어느 시점까지 볼지 정함 |
| 잠금 또는 버전 제어 | 잠금과 MVCC로 읽기와 쓰기 충돌을 제어해 격리 수준을 구현함 |
| 충돌 처리 정책 | 데드락과 직렬화 실패가 발생했을 때 대기할지 재시도할지 정함 |
| 업무 매핑 기준 | 화면 조회와 재고 차감과 결제 승인처럼 업무별로 필요한 격리 수준을 구분함 |

> 요약: 읽기 가시성은 잠금·MVCC가 구현하고 충돌 정책과 업무 위험이 격리 수준 선택을 결정함.

## Ⅵ. 실무 사례

1. 재고 차감 DB는 Serializable과 재시도를 적용하고 직렬화 실패율·재고 불일치 건수를 확인함
2. 목록 조회 DB는 Read Committed를 적용하고 재조회 불일치 건수·p95 응답 시간을 확인함

## Ⅶ. 결론

- 격리 수준은 업무가 허용하지 않는 읽기 이상과 잠금·재시도 비용을 기준으로 선택함
