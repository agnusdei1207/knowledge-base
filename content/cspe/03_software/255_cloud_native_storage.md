## Ⅰ. 개요
- 정의: 분산·복제·자동 프로비저닝을 통해 클라우드 워크로드의 저장 용량과 처리량을 확장하는 체계임
- 배경: MSA별 데이터 모델과 읽기·쓰기 부하 변화에 맞춰 저장소를 독립적으로 선택·확장할 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| DB 유형 | NoSQL, NewSQL, Serverless | 높음 |
| 스토리지 | Object Storage, SDS | 매우높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ App ] -> [ Database Service ] -> [ Storage Pool ]
    |             |                     |
  (MSA)     (Scale-out/Auto)     (S3/EBS/CSI)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 오브젝트 스토리지 | 비정형 데이터를 ID 기반으로 대량 저장 (S3 등) | 거대한 창고 |
| NoSQL | 스키마 없이 대규모 분산 처리에 특화된 DB | 칸막이 없는 수납장 |
| 분산 DB | 여러 노드에 데이터를 분산하여 가용성 확보 | 프랜차이즈 지점 |

> 요약: 오브젝트 스토리지·분산 DB·관리형 서비스로 데이터 유형별 저장과 확장 단위를 분리함

## Ⅲ. 절차
- ASCII 흐름도
  [데이터 성격 분석] -> [저장소 유형 선정] -> [샤딩/복제 설정] -> [상시 확장]
     (정형/비정형)         (SQL/NoSQL)         (Availability)      (Elasticity)

- 4단계 설명
1. 특성파악: 읽기/쓰기 비율, 데이터 모델, 일관성 요구 수준을 분석함
2. 서비스선택: 목적에 맞는 클라우드 관리형 서비스(Managed Service)를 선정함
3. 고가용성설계: 리전/존 간 복제(Replication)를 설정하여 장애 대비책 마련함
4. 모니터링: 부하에 따라 노드를 자동으로 늘리거나 성능 티어를 조정함

> 요약: 데이터 모델·일관성·부하 특성에 맞는 서비스를 선택하고 복제·확장 정책을 설정함

## Ⅳ. 문제점
- 클라우드 벤더별 고유 API 사용 시 타 클라우드로의 데이터 이전(Lock-in) 힘듦
- 분산 환경에서의 데이터 일관성(Consistency) 유지와 동기화 복잡도 증가함

## Ⅴ. 개선방안
- (단기) CAP 이론에 근거하여 비즈니스 요건에 맞는 일관성 모델을 선택함
- (중기) 오픈소스 기반 DB(PostgreSQL, Redis 등)의 관리형 서비스를 우선 활용함
- (장기) 클러스터 간 자동 복제 및 Failover를 지원하는 NewSQL 도입을 검토함

## Ⅵ. 전망
- 벡터 데이터베이스(Vector DB)가 AI 시대의 핵심 저장소로 급성장할 것임
- 컴퓨팅과 스토리지가 완전히 분리되어 각각 독립적으로 확장되는 구조 보편화됨
