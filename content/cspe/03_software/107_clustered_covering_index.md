## 미리 알고가기

- 클러스터드 인덱스는 데이터 저장 순서 자체를 인덱스 키 기준으로 맞추는 구조임
- 커버링 인덱스는 질의에 필요한 컬럼을 인덱스 안에서 모두 읽게 해 테이블 본문 재조회 횟수를 줄이는 구조임
- 둘 다 입출력을 줄이지만 적용 목적과 부작용이 서로 다름

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 클러스터드·커버링 인덱스는 데이터 배치와 테이블 접근 제거를 핵심 축으로 설명함
- 비교표는 입출력 절감 방식·적합 질의·주요 한계를 대비함
- 조회 DB는 페이지 분할률·테이블 재조회 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: 클러스터드 인덱스는 인덱스 키 순서로 데이터를 배치하고, 커버링 인덱스는 질의에 필요한 컬럼을 포함해 테이블 재조회를 제거하는 구조임
- **배경/필요성**: 범위 조회의 페이지 이동과 반복 조회의 테이블 접근을 줄이기 위해 데이터 배치와 포함 컬럼을 질의 패턴에 맞게 설계해야 함

## Ⅱ. 특징

- 클러스터드 인덱스는 범위 조회와 정렬 순서가 맞는 질의에서 효과가 큼
- 커버링 인덱스는 인덱스만 읽고 결과를 만들 수 있어 임의 접근 입출력을 줄임
- 클러스터드 인덱스는 키 변경과 페이지 분할에 민감함
- 커버링 인덱스의 key·include 컬럼이 늘면 인덱스 페이지 수와 INSERT·UPDATE 시 갱신량이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 클러스터드 인덱스 | 커버링 인덱스 |
|:---|:---|:---|
| I/O 절감 방식 | 인접 키 행을 같은·인접 페이지에 배치 | 조건·출력 컬럼을 인덱스에서 읽어 테이블 재조회 제거 |
| 적합 질의 | 날짜 범위 조회와 순차 정렬 조회 | 조회 컬럼이 고정된 화면 호출과 목록 조회 |
| 적용 결과 | 범위 스캔의 페이지 이동과 별도 정렬 감소 | 질의당 테이블 임의 접근 횟수 감소 |
| 주요 한계 | 키 선택이 나쁘면 분할과 조각화 비용이 커짐 | 컬럼을 과하게 넣으면 저장 공간과 쓰기 부담이 커짐 |

> 요약: 클러스터드 인덱스는 데이터 배치로 범위 조회 I/O를 줄이고, 커버링 인덱스는 필요한 컬럼을 포함해 테이블 재조회를 제거함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 클러스터드 키 | 데이터가 어떤 순서로 배치될지 정해 범위 탐색 비용을 좌우함 |
| 리프 페이지 배치 | 실제 데이터가 어떤 단위로 저장되는지 결정해 입출력 특성에 직접 영향을 줌 |
| 포함 컬럼 집합 | 커버링 인덱스가 어떤 질의를 인덱스만으로 처리할 수 있는지 정함 |
| 유지보수 정책 | 페이지 분할과 조각화와 인덱스 재구성을 관리해 성능 저하를 방지함 |

> 요약: 클러스터드 키와 리프 페이지가 데이터 배치를, 포함 컬럼이 커버링 범위를 결정하며 유지보수 정책이 쓰기 부담을 통제함.

## Ⅵ. 실무 사례

1. 주문 이력 DB는 시간 키로 클러스터드 인덱스를 구성하고 페이지 분할률·범위 조회 지연을 확인함
2. 목록 조회 API는 커버링 인덱스를 적용하고 테이블 재조회 비율·인덱스 용량을 확인함

## Ⅶ. 결론

- 클러스터드 인덱스는 데이터 배치를, 커버링 인덱스는 조회 컬럼 포함을 최적화해 입출력을 줄임
