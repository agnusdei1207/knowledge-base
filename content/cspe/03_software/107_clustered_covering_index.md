## 미리 알고가기

- 클러스터드 인덱스는 데이터 저장 순서 자체를 인덱스 키 기준으로 맞추는 구조임
- 커버링 인덱스는 질의에 필요한 컬럼을 인덱스 안에서 모두 읽게 해 테이블 본문 재조회 횟수를 줄이는 구조임
- 둘 다 입출력을 줄이지만 적용 목적과 부작용이 서로 다름

## Ⅰ. 개요

- **정의/개념**: 클러스터드 인덱스는 데이터의 저장 순서를 인덱스 키 기준으로 맞춰 범위 조회와 정렬 접근을 빠르게 만드는 구조이고, 커버링 인덱스는 특정 질의에 필요한 컬럼을 인덱스에 포함해 테이블 본문 접근을 줄이는 조회 최적화 방식임.
- **배경/필요성**: 일반 보조 인덱스만으로는 범위 조회나 반복 조회의 입출력을 충분히 줄이기 어려우므로, 저장 순서와 포함 컬럼을 함께 설계해 추가 최적화를 해야 할 때가 많음.

## Ⅱ. 특징

- 클러스터드 인덱스는 범위 조회와 정렬 순서가 맞는 질의에서 효과가 큼
- 커버링 인덱스는 인덱스만 읽고 결과를 만들 수 있어 임의 접근 입출력을 줄임
- 클러스터드 인덱스는 키 변경과 페이지 분할에 민감함
- 커버링 인덱스는 포함 컬럼이 많아질수록 크기와 유지 비용이 빠르게 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 클러스터드 인덱스 | 커버링 인덱스 |
|:---|:---|:---|
| 핵심 목적 | 저장 순서를 맞춰 범위 접근을 빠르게 함 | 필요한 컬럼을 인덱스에 담아 테이블 접근을 줄임 |
| 잘 맞는 질의 | 날짜 범위 조회와 순차 정렬 조회 | 조회 컬럼이 고정된 화면 호출과 목록 조회 |
| 주요 강점 | 범위 탐색과 정렬 비용을 함께 줄일 수 있음 | 짧은 조회에서 임의 접근 입출력을 크게 줄일 수 있음 |
| 주요 한계 | 키 선택이 나쁘면 분할과 조각화 비용이 커짐 | 컬럼을 과하게 넣으면 저장 공간과 쓰기 부담이 커짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 클러스터드 키 | 데이터가 어떤 순서로 배치될지 정해 범위 탐색 비용을 좌우함 |
| 리프 페이지 배치 | 실제 데이터가 어떤 단위로 저장되는지 결정해 입출력 특성에 직접 영향을 줌 |
| 포함 컬럼 집합 | 커버링 인덱스가 어떤 질의를 인덱스만으로 처리할 수 있는지 정함 |
| 유지보수 정책 | 페이지 분할과 조각화와 인덱스 재구성을 관리해 성능 저하를 막음 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +-------------+     +-------------+
| 대표 질의 선정  | --> | 키/포함 컬럼 설계 | --> | 인덱스 생성    | --> | 입출력 감소 검증 |
+-------------+     +----------------+     +-------------+     +-------------+
```

1. **대표 질의 선정**: 범위 조회와 반복 조회 중 어떤 질의를 줄일지 고름
2. **키와 포함 컬럼 설계**: 저장 순서 기준과 인덱스에 포함할 컬럼을 정함
3. **인덱스 생성**: 설계한 구조를 실제 테이블에 반영함
4. **입출력 감소 검증**: 조회 입출력 감소와 쓰기 부작용을 함께 확인함

## Ⅵ. 실무 적용 및 유의점

1. 시계열 주문 조회처럼 날짜 범위와 정렬이 중요한 업무에서는 클러스터드 키를 자주 바뀌지 않는 컬럼으로 잡고 페이지 분할률과 조각화율로 확인함.
2. 응답 컬럼이 거의 고정된 화면 호출에서는 커버링 인덱스가 효과적이지만 포함 컬럼이 많아지면 쓰기 비용이 커지므로 테이블 본문 재조회 비율과 인덱스 크기 증가율로 확인함.

## Ⅶ. 결론

클러스터드 인덱스와 커버링 인덱스는 모두 입출력을 줄이지만 저장 순서 최적화와 테이블 접근 제거라는 목적 차이를 구분해 써야 효과가 유지됨.
