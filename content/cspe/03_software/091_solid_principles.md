## Ⅰ. 개요
- 유연하고 유지보수가 쉬운 소프트웨어를 만들기 위한 5가지 핵심 설계 원칙임.
- Robert C. Martin이 정리하였으며, 결합도를 낮추고 응집도를 높이는 것이 목적임.
- 출제 의도: 원칙별 정의와 위반 사례 분석, 설계 개선 방안 제시 능력 평가.

## Ⅱ. 구성요소
- SOLID 5대 원칙
[S] | [O] | [L] | [I] | [D]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| SRP (단일 책임) | 하나의 클래스는 하나의 책임(변경 이유)만 가짐 | 맥가이버 칼 대신 전용 툴 |
| OCP (개방 폐쇄) | 확장에는 열려 있고, 수정에는 닫혀 있어야 함 | 플러그 앤 플레이 |
| LSP (리스코프 치환) | 자식은 언제나 부모를 대체할 수 있어야 함 | 타이어 규격 호환 |
| ISP (인터페이스 분리) | 사용하지 않는 메서드에 의존하도록 강제 금지 | 뷔페 대신 개별 메뉴 |
| DIP (의존 역전) | 구체화가 아닌 추상화에 의존해야 함 | 표준 소켓 사용 |
> 요약: 변경에 유연하게 대응할 수 있는 견고한 구조를 만드는 가이드임.

## Ⅲ. 절차
- SOLID 적용 설계 개선
[Code Analysis] -> [Violation Detection] -> [Refactoring] -> [Verification]

1. 코드 분석: 현재 클래스 구조와 의존 관계를 파악함.
2. 원칙 점검: 한 클래스에 너무 많은 기능이 있거나(SRP 위반) 하드코딩 확인.
3. 추상화 도입: 인터페이스나 추상 클래스를 도입하여 의존성을 분리함(DIP).
4. 모듈화: 기능을 쪼개고 공통 규격을 정의하여 확장성을 확보함(OCP).
> 요약: 위반 사례를 찾아 추상화와 분리 기법으로 설계를 정제함.

## Ⅳ. 문제점
- 과도한 원칙 적용으로 인한 클래스 수 급증 및 코드 복잡도 상승.

## Ⅴ. 개선방안
- 프로젝트 규모와 실용성을 고려한 점진적 적용(YAGNI 원칙 병행).

## Ⅵ. 전망
- 함수형 프로그래밍과 결합된 현대적 설계 패러다임에서의 SOLID 재해석 활발.
- AI 기반 리팩토링 도구가 SOLID 위반 사례를 자동 탐지하고 수정안 제안.
