## Ⅰ. 개요
- 마이크로소프트에서 개발한 윈도우 기반 애플리케이션 개발 및 실행 환경임
- 다중 언어 지원, 메모리 자동 관리, 강력한 클래스 라이브러리를 특징으로 함
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | CLR, BCL, 가비지 컬렉션(GC), .NET Core vs .NET 5+ 통합 | 만능 운영 체제 위의 멀티 툴킷 |

## Ⅱ. 구성요소
- 핵심 실행 엔진인 CLR과 방대한 라이브러리인 FCL로 구성됨
[C#, VB.NET, F#] --(컴파일)--> [IL (Intermediate Language)]
     [IL] --(JIT 컴파일)--> [CLR (Common Language Runtime)]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| CLR | 가비지 컬렉션, 예외 처리, 타입 안전성 등을 관리하는 런타임 | 공장의 자동 관리 시스템 |
| FCL / BCL | 파일 I/O, 네트워크, DB 접근 등 표준 클래스 라이브러리 | 표준화된 부품 라이브러리 |
| JIT 컴파일러 | 실행 시점에 IL 코드를 기계어로 변환하여 최적화 수행 | 실시간 통역가 |
> 요약: 언어 독립적이고 관리되는(Managed) 실행 환경을 제공함

## Ⅲ. 절차
- 컴파일에서 런타임 실행까지의 2단계 변환 절차임
[소스 코드] -> [IL 생성(컴파일)] -> [CLR 로드] -> [네이티브 코드 실행(JIT)]
- 4단계 설명
1) MSIL 변환: 다양한 언어의 소스코드를 공통 중간 언어(IL)로 컴파일함
2) 메타데이터 포함: 타입 정보와 선언을 포함하여 어셈블리(DLL/EXE) 파일 생성함
3) 메모리 관리: GC(Garbage Collector)가 세대별 관리를 통해 미사용 메모리 해제함
4) 보안 및 유효성 검사: 코드 접근 보안(CAS)을 통해 권한 확인 후 안전하게 실행함
> 요약: 강력한 도구(Visual Studio)와 연계하여 고속 개발 환경을 구현함

## Ⅳ. 문제점
- 과거 .NET Framework는 윈도우 종속적이며 플랫폼 확장이 어려웠음 (원인: 폐쇄적 생태계)
- 버전 업데이트 시 호환성 이슈 및 런타임 설치 부담이 존재함 (원인: 무거운 설치본)

## Ⅴ. 개선방안
- (단기) 크로스 플랫폼 지원을 위해 .NET Core 또는 .NET 5/6/7+ 통합 버전으로 전환함
- (중기) 컨테이너 환경 최적화를 위한 런타임 경량화 및 자가 포함 배포(Self-contained) 적용함
- (장기) 웹 어셈블리(Blazor) 등을 통한 브라우저 및 모바일 영역으로의 풀스택 확장함

## Ⅵ. 전망
- 클라우드 환경(Azure)과의 긴밀한 통합을 통해 고성능 백엔드 플랫폼으로 입지를 굳힐 것임
- AI 모델 배포를 위한 ML.NET 고도화 및 .NET 기반의 지능형 앱 생태계가 강화될 것임
