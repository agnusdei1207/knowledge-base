## Ⅰ. 개요
- **정의**: 한 번의 인증으로 연계된 복수 시스템에 추가 로그인 없이 접근하는 통합 인증 체계
- **배경/필요성**: 시스템마다 개별 인증을 요구하면 사용자 불편과 비밀번호 관리 부담이 증가함
- **비유**: 놀이공원 입장권 하나로 모든 놀이기구를 이용하는 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 통합 인증 아키텍처 이해 | 인증 위임·토큰 전파 메커니즘 | SSO와 Federation의 범위 차이 구분 필요 |

> 요약: 1회 인증으로 복수 시스템 접근을 가능하게 하는 통합 인증 아키텍처임

## Ⅱ. 구성요소
```text
User --> SP-A ----+
                  |----> IdP (Identity Provider)
User --> SP-B ----+        |
                      Token/Assertion
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| IdP | 사용자 인증을 수행하고 토큰/어서션을 발급하는 중앙 인증 서버 | 놀이공원 매표소 |
| SP | 서비스를 제공하며 IdP의 인증 결과를 신뢰하는 개별 시스템 | 각 놀이기구 |
| Token/Assertion | IdP가 발급한 인증 증거(SAML Assertion, OIDC ID Token 등) | 입장 팔찌 |
| Session | IdP와 SP 각각에서 유지되는 로그인 상태 | 팔찌 착용 상태 |
| Agent/Cookie | 브라우저에서 SSO 세션을 전달하는 매개체 | 팔찌 인식 센서 |

> 요약: IdP-SP 간 토큰 전파를 통해 단일 인증 세션을 복수 서비스로 확장하는 구조임

## Ⅲ. 절차
```text
User -> SP-A -> (미인증) -> IdP -> 인증 -> Token 발급
  |                                           |
  +--- SP-A <--- Token 검증 <--- 로그인 완료  |
  +--- SP-B ---> IdP(기인증) --> Token 재발급 -+
```
- 1단계: 사용자가 SP-A 접근 시, SP-A가 미인증 상태를 감지하고 IdP로 리다이렉트함
- 2단계: IdP에서 사용자 인증 후 토큰/어서션을 SP-A에 전달함
- 3단계: SP-A가 토큰을 검증하고 로컬 세션을 생성하여 서비스를 제공함
- 4단계: 사용자가 SP-B 접근 시, IdP가 기존 세션을 확인하고 추가 인증 없이 토큰을 발급함

> 요약: 최초 인증 후 IdP 세션을 재활용하여 추가 시스템에 자동 로그인하는 흐름임

## Ⅳ. 문제점
- 단일 장애점: IdP 장애 시 연계된 모든 시스템의 인증이 중단됨
- 세션 동기화 복잡성: SP별 세션 만료 시점이 다르면 로그아웃 불일치가 발생함
- 토큰 탈취 파급: 하나의 토큰 탈취로 연계된 모든 시스템에 무단 접근 가능해짐

> 요약: 단일 장애점·세션 불일치·토큰 탈취 파급이 핵심 위험 요소임

## Ⅴ. 개선방안
1. 단기: IdP 이중화(Active-Standby) 구성으로 가용성 확보
2. 중기: 글로벌 로그아웃 프로토콜(SLO) 적용으로 세션 동기화 보장
3. 장기: 토큰 바인딩(Token Binding) 및 MFA(175 참조) 연계로 탈취 시 재사용 차단

> 요약: IdP 이중화·SLO 적용·토큰 바인딩+MFA로 단계적 보완이 필요함

## Ⅵ. 전망
- 발전 방향: OIDC 기반 SSO가 SAML을 대체하며 클라우드 환경 표준으로 자리잡고 있음
- 기술사적 판단: 멀티클라우드·하이브리드 환경에서 Federation 기반 SSO 수요가 증가함
- 기술사 제언: IdP 자체 보안 강화와 함께 Zero Trust 모델과의 연계 설계가 필요함
