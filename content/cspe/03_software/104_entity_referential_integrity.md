## 미리 알고가기

- 개체 무결성은 기본키가 NULL이 아니고 유일해야 한다는 규칙임
- 참조 무결성은 외래키가 유효한 부모 키를 참조해야 한다는 규칙임
- 두 무결성은 관계형 DB에서 식별과 연결의 신뢰성을 담당함

## Ⅰ. 개요

- **정의/개념**: 개체 무결성은 각 행이 기본키로 명확히 식별되어야 한다는 규칙이고, 참조 무결성은 자식 테이블의 외래키가 존재하는 부모 키를 참조하거나 허용된 NULL 상태를 가져야 한다는 관계 규칙임
- **배경/필요성**: 테이블이 많아질수록 행 식별과 테이블 간 연결이 흔들리면 조회 오류와 고아 데이터와 삭제 파급 문제가 커지므로, 기본적인 관계 규율을 명확히 유지해야 함

## Ⅱ. 특징

- 개체 무결성은 중복 행과 식별 불가능 상태를 차단함
- 참조 무결성은 부모·자식 관계의 의미 일관성을 유지함
- 삭제와 갱신 규칙을 어떻게 둘지에 따라 운영 편의와 안전성이 달라짐
- 무결성 위반은 애플리케이션 로직보다 데이터 구조 문제로 확산 범위가 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | 개체 무결성 | 참조 무결성 |
|:---|:---|:---|
| 핵심 규칙 | 기본키는 유일하고 NULL 불가 | 외래키는 유효한 부모 키를 참조 |
| 주 대상 | 단일 테이블 식별 | 테이블 간 관계 연결 |
| 방지 문제 | 중복·식별 실패 | 고아 데이터·관계 불일치 |
| 주요 수단 | PRIMARY KEY | FOREIGN KEY, CASCADE 정책 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Primary Key | 각 행을 유일하게 식별해 개체 무결성을 형성함 |
| Foreign Key | 부모 행과의 연결을 정의해 참조 무결성을 보장함 |
| Parent-Child Policy | 삭제와 갱신 시 cascade와 restrict와 set null 동작을 결정함 |
| Integrity Check Flow | 저장과 삭제와 마이그레이션 시점마다 위반을 검사해 관계 품질을 유지함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키 설계        | --> | 관계 연결      | --> | 저장/삭제 검증  | --> | 위반 차단/조정  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 설계**: 기본키와 외래키를 정의함
2. **관계 연결**: 부모와 자식 테이블의 참조 관계를 선언함
3. **저장과 삭제 검증**: 변경 시 무결성 위반 여부를 검사함
4. **위반 차단과 조정**: 허용 정책에 맞게 실패 또는 연쇄 처리를 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 기본키 설계가 불안정하면 행 식별이 흔들려 참조 무결성 관리까지 연쇄적으로 복잡해질 수 있음
   - 해결방안: stable key policy를 수립하고 duplicate key incident count와 key change frequency로 검증함
2. 문제: cascade 정책을 업무 의미 없이 적용하면 부모 삭제가 예상보다 넓은 데이터 손실로 이어질 수 있음
   - 해결방안: delete policy review를 수행하고 cascade impact predictability와 orphan record count로 검증함
3. 문제: 대량 적재나 마이그레이션에서 무결성 점검을 우회하면 사후 정리 비용이 폭증할 수 있음
   - 해결방안: staged load validation을 적용하고 load-time integrity error rate와 remediation lead time으로 검증함

## Ⅶ. 적용 사례

- 회원·주문 시스템에서는 안정적 키 정책을 운영하고 확인 지표는 duplicate key incident count와 key change frequency임
- 마스터 데이터 삭제 정책에서는 연쇄 영향 검토를 수행하고 확인 지표는 cascade impact predictability와 orphan record count임
- 데이터 전환 프로젝트에서는 단계적 적재 검증을 적용하고 확인 지표는 load-time integrity error rate와 remediation lead time임

## Ⅷ. 결론

개체 무결성과 참조 무결성은 관계형 데이터의 최소 질서이므로 성능이나 편의보다 먼저 지켜야 할 구조 규칙임.
