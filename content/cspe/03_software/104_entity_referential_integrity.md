## 미리 알고가기

- 개체 무결성은 기본키가 비어 있지 않고 중복되지 않아야 한다는 규칙임
- 참조 무결성은 자식 테이블의 외래키가 존재하는 부모 키를 가리켜야 한다는 규칙임
- 두 규칙이 무너지면 행을 식별하지 못하거나 고아 데이터가 생김

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 개체·참조 무결성은 기본키와 외래키 규칙을 핵심 축으로 설명함
- 비교표는 통제 범위·방지 대상·대표 수단을 대비함
- 업무 DB와 데이터 이관은 중복 키·고아 데이터 건수로 검증함

## Ⅰ. 개요

- **정의/개념**: 개체 무결성은 기본키의 유일성과 NULL 금지를, 참조 무결성은 외래키와 부모 후보키의 유효한 관계를 강제하는 규칙임
- **배경/필요성**: 중복 키와 식별 불가 행·고아 데이터를 방지하기 위해 기본키와 외래키 규칙을 데이터베이스에서 강제해야 함

## Ⅱ. 특징

- 개체 무결성은 중복 행과 식별 불가 상태를 방지함
- 참조 무결성은 부모와 자식의 연결이 끊어지지 않게 함
- 삭제와 갱신 정책을 어떻게 두느냐에 따라 안전성과 운영 편의가 달라짐
- 한 번 무너지면 개별 화면 오류를 넘어 전체 데이터 신뢰성 문제로 번짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 개체 무결성 | 참조 무결성 |
|:---|:---|:---|
| 규칙 | 기본키는 NULL·중복 불가 | 외래키는 NULL 정책을 따르거나 존재하는 부모 후보키 참조 |
| 관리 대상 | 한 테이블 안의 행 식별 | 두 테이블 사이의 관계 연결 |
| 방지 대상 | 중복 행과 식별 실패 | 고아 데이터와 잘못된 참조 |
| 대표 수단 | PRIMARY KEY | FOREIGN KEY와 삭제·갱신 정책 |

> 요약: 개체 무결성은 기본키로 행을 식별하고, 참조 무결성은 외래키로 부모·자식 관계를 유지함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기본키 | 각 행을 유일하게 식별해 개체 무결성의 기준이 됨 |
| 외래키 | 부모 행과의 연결을 정의해 참조 무결성을 강제함 |
| 부모-자식 처리 정책 | 삭제와 갱신 시 연쇄 삭제와 제한과 NULL 처리 중 어떤 동작을 할지 정함 |
| 검증 절차 | 저장과 삭제와 이관 과정마다 위반 여부를 확인해 관계 품질을 유지함 |

> 요약: 기본키와 외래키를 정의하고 부모·자식 처리 정책과 검증 절차로 키 관계를 유지함.

## Ⅵ. 실무 사례

1. 회원·주문 DB는 기본키와 외래키 삭제 정책을 적용하고 중복 키·고아 데이터 건수를 확인함
2. 데이터 이관은 적재 후 외래키를 재검증하고 고아 데이터 건수·보정 시간을 확인함

## Ⅶ. 결론

- 개체 무결성은 행의 식별을, 참조 무결성은 부모·자식 키 관계를 통제함
