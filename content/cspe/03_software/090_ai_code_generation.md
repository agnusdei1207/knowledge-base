# 📖 【암기용】 개념 완전 이해

> 목적: AI 코드 생성을 개발자 보조, 품질 검증, 라이선스·보안 통제의 결합으로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: AI 코드 생성은 LLM이 주석·프롬프트·문맥을 바탕으로 코드와 테스트를 제안하는 개발 보조 방식
- **왜 필요한가**: 반복 코드, 테스트 초안, API 사용 예시는 개발 시간을 차지하지만 창의적 설계보다 자동화 적합성이 높다.
- **핵심 직관**: 숙련 개발자 옆의 페어 프로그래머처럼 초안을 제안하지만, 최종 책임은 리뷰·테스트·라이선스 검증을 수행하는 사람에게 있음.

## 깊이 이해
- **배경·문제의식**: 개발 생산성 요구가 커졌지만 신규 프레임워크, 보일러플레이트, 테스트 작성은 반복 작업 비중이 높음.
- **작동 원리**: IDE 확장이 현재 파일, 주변 코드, 주석, 프롬프트를 모델에 전달하고 모델이 다음 코드, 함수, 테스트, 리팩터링 제안을 생성함.
- **비유**: 자동완성 사전이 단어를 제안하던 수준에서 문단 초안을 쓰는 비서로 바뀐 것과 같지만, 사실 확인과 문체 수정은 작성자가 해야 함.
- **구체 예시**: REST 컨트롤러 주석을 입력하면 Copilot이 DTO, validation, unit test 초안을 생성하고 개발자는 SAST·테스트·코드리뷰로 검증함.
- **흔한 오해·주의점**: AI가 만든 코드는 컴파일 성공과 업무 적합성이 다르며, 환각 API, 취약 패턴, 라이선스 유사 코드가 포함될 수 있음.

## 연결 개념
- AI Pair Programming: 개발자와 AI의 협업 방식
- SAST/SCA: 생성 코드의 보안·라이선스 검증
- Code Review: 최종 품질 책임 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: AI 코드 생성 문제는 생산성만 쓰면 감점이며, 환각, 보안, 라이선스, 리뷰 책임, 측정 지표를 함께 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI 코드 생성은 LLM이 개발 문맥을 기반으로 코드·테스트·문서 초안을 생성하는 AI pair programming 기술이다.
> 2. **가치**: 반복 코드와 테스트 초안 작성 시간을 줄이고 개발자는 설계, 검증, 리뷰, 예외 처리에 시간을 배분한다.
> 3. **판단 포인트**: 생성 코드는 hallucination, 취약 코드, 라이선스 충돌, 사내 코드 유출 리스크를 CI·리뷰·정책으로 통제해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 개발도구 이해 확인 | Copilot, LLM, context, prompt, completion | 자동완성과 동일하게 설명하지 않음 |
| 품질·보안 통제 확인 | hallucination, SAST, SCA, code review | 생산성 효과만 나열하지 않음 |
| 조직 적용 판단 확인 | 정책, 측정지표, 금지 데이터, 책임자 | 생성 코드 책임을 AI에 전가하지 않음 |
> 요약: AI 코드 생성은 개발 보조 기술이며, 최종 품질은 사람의 리뷰와 자동 검증 파이프라인으로 보증해야 한다.

## Ⅰ. 개요 및 필요성

AI 코드 생성은 LLM 기반 개발 보조 기술이다.
반복 구현, 테스트 초안, API 사용 예시는 자동화 가치가 높지만 생성 코드의 업무 적합성과 안전성은 검증이 필요하다.
따라서 도입 답안은 생산성, 품질, 보안, 라이선스, 책임소재를 함께 다뤄야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
IDE/Repository Context -> Prompt -> LLM Completion
-> Developer Review -> Unit Test/SAST/SCA
-> Pull Request -> Code Review -> Merge Policy
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| Context | 주변 코드·주석·파일 정보 제공 | 민감정보 제외 정책 |
| Prompt | 의도와 제약 입력 | 테스트·예외 조건 명시 |
| Completion | 코드·테스트 초안 생성 | API 존재성, 컴파일 검증 |
| Guardrail | 리뷰·검사·정책 통제 | SAST, SCA, secret scan |
> 요약: AI 코드 생성 구조는 모델 제안과 개발자 검증, CI 통제가 결합된 개발 흐름이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
개발 의도 작성 -> 모델이 코드 후보 생성 -> 개발자 수정
-> 로컬 테스트 실행 -> SAST/SCA/secret scan
-> PR 리뷰 -> 품질 지표 측정 -> 정책 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 주석·함수명·프롬프트 작성 | 요구사항 ID 또는 이슈 링크 |
| 2 | 코드·테스트 후보 생성 | 컴파일 오류 0건 |
| 3 | 개발자 의미 검토 | business rule review |
| 4 | 자동 검사 수행 | SAST high 0건, SCA 정책 통과 |
| 5 | PR 리뷰와 병합 | 리뷰 승인 2인 또는 CODEOWNERS |
> 요약: AI 생성 코드는 제안, 수정, 테스트, 보안·라이선스 검사, PR 리뷰를 통과해야 병합한다.

## Ⅳ. 특징

| 구분 | 전통 개발 | AI 코드 생성 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 작성 방식 | 사람이 전량 작성 | AI 초안+사람 검증 | 반복 코드 소요시간 20~40% 절감 목표 |
| 품질 리스크 | 사람 실수 중심 | 환각 API·취약 패턴 추가 | SAST high 0건 |
| 라이선스 | 의존성 중심 검토 | 유사 코드·SCA 검토 필요 | 허용 라이선스 목록 |
| 책임 | 작성자 책임 | 리뷰어·병합자 책임 유지 | PR 승인 기록 |
> 요약: AI 코드 생성은 초안 작성 시간을 줄이지만 품질 책임과 검증 절차는 기존보다 더 명시되어야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | IDE 자동완성 | LLM 기반 함수·테스트 생성 | 반복 패턴 많은 코드베이스 |
| 비용/규모 | 개발자 수작업 | 도구 구독+검증 자동화 | 월 PR 100건 이상 조직 |
| 운영/위험 | 일반 코드리뷰 | AI 사용 정책과 Guardrail | 민감정보·라이선스 리스크 |
| 품질 | 테스트 작성 지연 | 테스트 초안 생성 가능 | coverage 목표 80% 이상 |
> 요약: AI 코드 생성은 반복 구현 비중이 크고 CI 검증 체계가 갖춰진 조직에서 우선 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Hallucination | 존재하지 않는 API 제안 | 컴파일·계약 테스트 필수 | build fail rate |
| 취약 코드 | 안전하지 않은 예제 학습 | SAST, dependency scan | high 취약점 0건 |
| 라이선스 충돌 | 공개 코드 유사 생성 | SCA와 유사도 검사 | 정책 위반 0건 |
| 정보 유출 | 민감 코드 prompt 포함 | 금지 데이터 정책, enterprise 설정 | secret scan 0건 |
> 요약: AI 코드 생성 리스크는 환각, 취약점, 라이선스, 정보유출을 CI와 정책으로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 생산성 | PR 리드타임 20% 단축 | DORA lead time |
| 품질 | 결함 재오픈율 5% 이하 | defect tracker |
| 보안 | SAST high 0건 | CI 보안 검사 |
| 채택률 | 주간 활성 개발자 70% | 도구 사용 로그 |
> 요약: 도입 효과는 리드타임, 결함 재오픈율, 보안 검사 결과, 개발자 채택률로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 사용 정책에 민감정보 입력 금지, 허용 저장소, 라이선스 검토 기준, PR 책임자를 명시함.
2. 생성 코드는 unit test, SAST high 0건, SCA 정책 통과, secret scan 0건을 병합 조건으로 설정함.
3. 4주 파일럿에서 PR 리드타임, coverage, 결함 재오픈율, 개발자 만족도 점수를 측정해 확대 여부를 판단함.

**결론 (2줄):**
- 기술사 판단: 반복 구현과 테스트 초안 비중이 큰 조직은 AI 코드 생성을 적용하되, 안전·라이선스·리뷰 정책이 없는 조직은 파일럿부터 시작함.
- 향후 방향: AI 코드 생성은 IDE 보조를 넘어 요구사항, 테스트, 리뷰, 배포 정책과 연결된 SDLC 자동화로 확장됨.
