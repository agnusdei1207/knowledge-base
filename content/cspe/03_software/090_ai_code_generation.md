## 미리 알고가기

- AI 코드 생성은 자연어 요구와 코드 문맥을 바탕으로 구현 후보를 제안하는 개발 보조 방식임
- 코드 문맥은 현재 파일, 관련 함수, 사용 중인 API 같은 주변 정보를 뜻함
- IDE 자동완성은 편집기 안에서 토큰이나 구문을 이어 쓰도록 돕는 기존 자동완성 기능임
- 자동 생성 코드도 최종 품질과 책임은 개발 조직이 짐
- GitHub Copilot은 IDE와 코드 저장소 문맥을 사용하는 AI 코드 생성 도구의 대표 사례임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- AI 코드 생성은 요구·코드 문맥, 모델 제안, 정책 가드레일, 개발자 검증을 핵심 축으로 설명함
- 비교표는 IDE 자동완성과 AI 생성의 제안 범위·생성 근거·오류 유형·검증 범위를 대비함
- 백엔드 서비스와 보안 저장소의 생성 코드는 테스트 통과율·정책 위반률로 검증함

## Ⅰ. 개요

- **정의/개념**: AI 코드 생성은 언어모델이 자연어 요구·코드 문맥·API 패턴으로 구현·테스트·리팩터링 후보를 제안하는 개발 보조 기술임
- **배경/필요성**: 반복 구현과 API 탐색 시간을 줄이면서 코드 책임을 유지하기 위해 문맥 제공과 사람 검증을 결합한 개발 절차가 필요함

## Ⅱ. 특징

- 반복 코드·테스트 초안·문서 후보를 생성함
- 코드베이스 문맥과 프롬프트 품질에 따라 결과 편차가 큼
- 보안 취약 패턴과 비표준 구현을 그대로 제안할 위험이 있음
- 생성 결과를 코드 리뷰·테스트·보안 검사 후 저장소에 반영함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적 IDE 자동완성 | AI 코드 생성 |
|:---|:---|:---|
| 제안 범위 | 토큰·구문 수준의 완성 후보를 제시함 | 함수·테스트·리팩터링 단위의 코드를 제시함 |
| 생성 근거 | 언어 문법·심볼·정적 API 정보를 사용함 | 요구 설명·주변 코드·학습된 코드 패턴을 사용함 |
| 오류 유형 | 미완성 심볼·타입·API 불일치가 발생함 | 환각 API·취약 패턴·라이선스·비밀 노출이 발생함 |
| 검증 범위 | 구문·타입·API 일치를 확인함 | 요구·테스트·취약점·라이선스·비밀 노출을 확인함 |

> 요약: IDE 자동완성은 문법·심볼로 구문을 제안하고, AI 코드 생성은 요구·코드 문맥으로 함수 단위 후보를 생성함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 요구와 문맥 입력 | 작업 목적과 주변 코드 정보가 생성 범위와 출력 품질에 영향을 줌 |
| 모델 추론 | 언어모델이 구현 후보와 설명과 테스트 초안을 생성함 |
| 정책 가드레일 | 금지 패턴과 민감 코드와 라이선스 정책을 점검해 위험 출력을 걸러냄 |
| 사람 검토 순환 | 개발자가 생성 결과를 검토하고 수정해 실제 코드 품질을 확정함 |

> 요약: 요구·코드 문맥을 모델에 제공하고 정책 가드레일과 개발자 검토로 저장소 반영 여부를 결정함.

## Ⅴ. 원리 및 절차 흐름도

1. **요구와 문맥 입력**: 작업 목적과 관련 코드와 제약을 제공함
2. **코드 초안 생성**: 구현 후보와 테스트 초안을 생성함
3. **정책과 품질 점검**: 보안과 라이선스와 규약 위반 여부를 검토함
4. **개발자 확정**: 리뷰와 수정 후 코드베이스에 반영함

> 요약: 요구·코드 문맥으로 구현 후보를 생성하고 정책·품질 점검과 개발자 검토를 거쳐 저장소에 반영함.

## Ⅵ. 실무 사례

1. 백엔드 API 저장소는 작업 문맥과 단위 테스트 템플릿을 제공하고 테스트 통과율·리뷰 수정률을 확인함
2. 보안 코드 저장소는 SAST·라이선스·비밀 검사를 게이트로 적용하고 정책 위반률·리뷰 결함률을 확인함

## Ⅶ. 결론

- AI 코드 생성은 코드 문맥과 정책 가드레일을 제공하고 개발자 검증 후 결과를 반영함
