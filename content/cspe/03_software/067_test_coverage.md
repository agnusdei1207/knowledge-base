## 미리 알고가기

- 테스트 커버리지는 테스트가 코드 구조를 얼마나 실행했는지 나타내는 지표임
- MC/DC는 각 조건이 결과에 독립적으로 영향을 주는지 확인하는 커버리지 기준임
- 높은 커버리지가 곧 높은 품질을 보장하지는 않음

## 작성 근거(검토용)

- 테스트 커버리지는 검증 대상, 확인 공백, 설계 부담, 적용 환경을 핵심 비교축으로 선정함
- 구성은 기준 선택, 실행 계측, 공백 분석, 위험 기반 목표의 관계를 중심으로 제시함
- 실무 판단은 분기 커버리지, 운영 유출 결함률, 중요 경로 커버리지, 테스트 설계시간으로 구체화함

## Ⅰ. 개요

- **정의/개념**: 테스트 커버리지는 작성된 테스트가 코드의 구문·분기·조건·경로를 실행한 비율을 측정하는 구조 기반 지표임
- **배경/필요성**: 테스트 수가 많아도 중요한 분기와 조건이 실행되지 않을 수 있으므로 구조상 검증 공백을 측정할 기준이 필요함

## Ⅱ. 특징

- 구문 커버리지는 실행된 문장을 측정하며, 분기의 참·거짓 실행 여부는 구분하지 않음
- 분기·조건·경로 커버리지로 갈수록 필요한 테스트 사례 조합이 늘어남
- MC/DC는 안전성이 중요한 분야에서 조건 독립성을 확인하는 데 쓰임
- 수치 목표만 적용하면 결과 검증식 없이 코드를 실행하는 테스트가 늘 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 구문 커버리지 | 분기 커버리지 | 조건·경로 커버리지 | MC/DC |
|:---|:---|:---|:---|:---|
| 검증 대상 | 코드 문장 실행 | 참·거짓 분기 실행 | 조건값·실행 경로 조합 | 조건별 결과 독립 영향 |
| 충족 조건 | 각 문장을 한 번 이상 실행 | 각 분기의 참·거짓 실행 | 조건값·경로 조합 실행 | 각 조건의 독립 영향 입증 |
| 구조상 한계 | 분기 누락 가능 | 복합 조건 조합 누락 | 경로 수 증가에 따른 설계 비용 | 조건 독립성 설계·도구 비용 |
| 대표 환경 | 단위 테스트 실행 범위 확인 | 서비스 제어 흐름 검증 | 중요 계산·복합 조건 경로 검증 | 항공·제어 안전 로직의 MC/DC 검증 |

> 요약: 구문에서 분기·조건·경로·MC/DC로 갈수록 검증 강도와 테스트 설계 비용이 함께 증가함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 커버리지 기준 | 무엇을 커버한 것으로 볼지 기준을 정해 수치 해석을 일관되게 만듦 |
| 실행 계측 | 코드 실행 정보를 수집해 실제 테스트 통과 경로를 측정함 |
| 공백 분석 | 실행되지 않은 구문과 분기와 조건을 찾아 보완 대상을 정함 |
| 위험 기반 목표 | 모듈 중요도에 따라 서로 다른 커버리지 목표를 적용해 비용을 통제함 |

> 요약: 선택한 커버리지 기준으로 실행 경로를 계측하고 미실행 영역을 위험도에 따라 보강함.

## Ⅵ. 실무 사례

1. 일반 서비스는 분기 커버리지와 뮤테이션 점수를 함께 보고 운영 유출 결함률을 확인함
2. 안전 제어 모듈은 중요 경로에 MC/DC를 적용하고 중요 경로 커버리지·테스트 설계시간을 확인함

## Ⅶ. 결론

테스트 커버리지는 구문·분기·조건·경로의 미실행 영역을 찾아 구조상 검증 공백을 보완하는 지표임
