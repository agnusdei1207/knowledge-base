# 📖 【암기용】 개념 완전 이해

> 목적: 테스트 커버리지를 숫자 자체가 아니라 검증 범위 지표로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 테스트가 코드나 요구사항의 어느 범위까지 실행·검증했는지 나타내는 지표
- **왜 필요한가**: 테스트가 모두 통과해도 실행되지 않은 문장, 분기, 조건, 경로가 남을 수 있음. 커버리지는 그런 미검증 영역을 찾아 추가 테스트를 설계하게 해줌.
- **핵심 직관**: 시험 범위 중 몇 쪽을 실제로 풀어봤는지 표시하는 지도이며, 정답을 보장하는 성적표는 아님.

## 깊이 이해
- **배경·문제의식**: 테스트 통과율만 보면 검증 범위가 넓은지 알 수 없음. statement coverage는 줄 실행 여부, branch coverage는 if true/false, condition coverage는 복합 조건의 각 항목, path coverage는 실행 경로 조합을 봄.
- **작동 원리**: 테스트 실행 중 계측 도구가 코드 실행 정보를 수집하고 전체 대상 대비 실행된 항목 비율을 계산함. 항공·자동차 안전 영역은 MC/DC처럼 각 조건이 결과에 독립적으로 영향을 주는지 확인함.
- **비유**: 건물 안전 점검에서 방마다 들어가 봤는지, 문마다 열어 봤는지, 비상구 경로까지 걸어 봤는지를 구분하는 것임.
- **구체 예시**: `if (age >= 19 && paid)`는 statement 100%여도 paid가 false인 경우를 안 보면 condition coverage가 낮음. MC/DC는 age와 paid가 각각 결과를 바꾸는 사례를 요구함.
- **흔한 오해·주의점**: 커버리지 100%는 결함 0건을 뜻하지 않음. assertion이 약하거나 요구사항이 틀리면 코드 실행 범위가 넓어도 결함을 놓침.

## 연결 개념
- White-box Testing: 코드 구조 기반 커버리지 측정
- MC/DC: 안전 필수 시스템에서 쓰는 조건 독립성 기준
- Mutation Testing: 커버리지 착시를 보완하는 테스트 적합성 평가

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 테스트 커버리지는 품질 보증 수치가 아니라 미검증 영역을 찾는 지표이며 risk-based testing과 함께 해석해야 함.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 테스트 커버리지는 테스트가 코드, 조건, 경로, 요구사항 중 어느 범위를 실행·검증했는지 나타내는 비율임.
> 2. **가치**: statement, branch, condition, path, MC/DC 지표로 누락 영역을 식별하고 추가 테스트 우선순위를 정함.
> 3. **판단 포인트**: 커버리지 수치만 높이는 coverage illusion을 경계하고 assertion 품질과 결함 유출률을 함께 봐야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 커버리지 유형 이해 확인 | statement, branch, condition, path, MC/DC | line coverage만 설명 |
| 지표 해석 능력 확인 | coverage illusion, assertion, mutation score | 100%면 결함 없음으로 단정 |
| 테스트 전략 판단 확인 | risk-based testing, safety-critical 기준 | 모든 코드에 path coverage 요구 |

> 요약: 커버리지 문제는 유형별 측정 범위와 지표 한계를 함께 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

테스트 커버리지는 테스트가 대상 코드나 요구사항을 얼마나 실행·검증했는지 측정하는 지표이다. 테스트 통과 결과만으로는 미실행 분기와 경계 조건을 알 수 없으므로 계측 기반 측정이 필요하다. 커버리지는 누락 영역 발견과 테스트 보강 우선순위 판단에 사용된다.

---

## Ⅱ. 구조 및 구성요소

```text
Source Code/Test Basis -> Instrumentation -> Test Execution
Execution Data -> Coverage Report -> Gap Analysis
Gap Analysis -> Additional Test -> Risk Decision
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Coverage Target | 코드, 조건, 경로, 요구사항 | 측정 기준별 분모 설정 |
| Instrumentation | 실행 지점 수집 | JaCoCo, Istanbul, coverage.py |
| Coverage Report | 실행 비율과 누락 위치 표시 | line, branch, condition |
| Risk Decision | 추가 테스트 우선순위 판단 | 위험 기반 보완 |

> 요약: 커버리지 구조는 계측, 실행, 리포트, 누락 분석을 거쳐 테스트 보강 판단으로 이어진다.

---

## Ⅲ. 동작원리 및 흐름도

```text
측정 기준 선택 -> 코드 계측 -> 테스트 실행
-> 실행 데이터 수집 -> 커버리지 계산
-> 미검증 영역 분석 -> 테스트 추가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | statement, branch, condition, MC/DC 중 기준 선택 | 시스템 위험도 반영 |
| 2 | 빌드 단계에서 계측 도구 적용 | report 생성 성공 |
| 3 | 자동 테스트 실행과 실행 지점 수집 | flaky test 2% 이하 |
| 4 | 미실행 문장·분기·조건 확인 | branch 80% 이상 |
| 5 | 위험 높은 누락 영역에 케이스 추가 | 결함 유출률 감소 |

> 요약: 커버리지는 기준 선택 후 계측과 실행 데이터를 통해 누락 영역을 찾고 위험 기반으로 테스트를 보강한다.

---

## Ⅳ. 특징

| 구분 | 단순 통과율 | 테스트 커버리지 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 측정 대상 | 테스트 성공/실패 | 실행된 코드·조건·경로 | line 80%, branch 70% |
| 결함 판단 | pass면 통과 | 미검증 영역 표시 | assertion 품질 별도 확인 |
| 고위험 시스템 | 일반 지표 사용 | MC/DC 적용 | DO-178C Level A 기준 |
| 한계 | 범위 정보 부족 | coverage illusion 가능 | mutation score 보완 |

> 요약: 커버리지는 누락 영역 식별 지표이며 결함 검출력은 assertion과 mutation testing으로 보완해야 한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | pass/fail 중심 | 실행 범위 계측 | 변경 영향이 큰 모듈 |
| 비용/성능 | 수동 리뷰 | 자동 리포트와 gate | CI 10분 이하 유지 |
| 운영/위험 | 운영 결함 후행 파악 | 누락 분기 사전 식별 | 장애 RCA에 조건 누락 반복 시 |
| 안전 기준 | branch coverage | MC/DC | 항공, 자동차, 의료 제어 SW |

> 요약: 커버리지 기준은 시스템 위험도와 실행 비용에 맞춰 line, branch, condition, MC/DC를 차등 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Coverage 착시 | 실행만 하고 검증 약함 | assertion review, mutation test | mutation score 70% 이상 |
| 수치 게임 | 무의미한 테스트 추가 | risk-based target 설정 | high-risk coverage 95% |
| 경로 폭증 | path 조합 증가 | 경계·위험 경로 우선 | selected path 근거 |
| CI 지연 | 계측과 테스트 증가 | 증분 테스트, 병렬화 | CI duration 10분 이하 |

> 요약: 커버리지 리스크는 착시와 비용 증가이며 assertion 품질, 위험도, CI 시간으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 구조 범위 | statement 80%, branch 70% 이상 | coverage report |
| 조건 검증 | 복합 조건별 true/false 포함 | condition report |
| 안전 기준 | MC/DC 대상 100% | safety test report |
| 결함 보완 | escaped defect 5% 이하 | incident RCA |

> 요약: 커버리지 효과는 구조 범위, 조건 검증, 안전 기준 충족, 운영 유출 결함으로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 일반 업무 시스템은 line coverage 80%, branch coverage 70%를 CI gate로 설정하고 신규 코드 기준을 별도 측정함.
2. 복합 조건이 많은 정산·권한 모듈은 condition coverage를 추가하고 안전 필수 제어 로직은 MC/DC 100%를 적용함.
3. coverage 80% 이상이어도 mutation score 70% 미만이면 assertion을 보강하고 운영 결함 RCA 결과를 테스트 케이스로 환류함.

**결론 (2줄):**
- 기술사 판단: 커버리지는 품질 완성 지표가 아니라 누락 탐지 지표이며, 위험 기반 테스트와 결함 지표를 함께 적용해야 함.
- 향후 방향: 커버리지는 변경 영향 분석, AI 테스트 추천, mutation testing과 결합해 테스트 우선순위 산정 지표로 확대됨.
