## 미리 알고가기

- 테스트 커버리지는 테스트가 코드 구조를 얼마나 실행했는지 나타내는 지표임
- MC/DC는 각 조건이 결과에 독립적으로 영향을 주는지 확인하는 강한 커버리지 기준임
- 높은 커버리지가 곧 높은 품질을 보장하지는 않음

## Ⅰ. 개요

- **정의/개념**: 테스트 커버리지는 작성된 테스트가 코드의 구문과 분기와 조건과 실행 경로를 어느 정도 실행했는지 정량화하는 구조 기반 검증 지표 체계임.
- **배경/필요성**: 테스트 수가 많아도 중요한 분기와 조건이 실행되지 않을 수 있으므로, 구조 관점에서 검증 공백을 확인할 기준이 필요함.

## Ⅱ. 특징

- 구문 커버리지는 실행된 문장을 측정하며, 분기의 참·거짓 실행 여부는 구분하지 않음
- 분기와 조건과 경로 커버리지는 검증 강도는 높아지지만 설계 비용도 늘어남
- MC/DC는 안전성이 중요한 분야에서 조건 독립성을 확인하는 데 쓰임
- 수치 목표만 따라가면 의미 없는 테스트가 늘 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 구문 커버리지 | 분기 커버리지 | 조건·경로 커버리지 | MC/DC |
|:---|:---|:---|:---|:---|
| 검증 대상 | 코드 문장이 한 번이라도 실행됐는지 봄 | 각 분기의 참과 거짓이 모두 실행됐는지 봄 | 개별 조건 값과 실행 경로 조합을 더 강하게 봄 | 각 조건이 결과에 독립 영향을 주는지 봄 |
| 확인 범위 | 실행되지 않은 문장 | 실행되지 않은 참·거짓 분기 | 실행되지 않은 조건 값·경로 조합 | 결과에 독립 영향을 주지 못한 조건 |
| 구조상 한계 | 얕은 검증이라 중요한 분기를 놓칠 수 있음 | 복합 조건의 미묘한 조합은 놓칠 수 있음 | 경로 수가 급격히 늘어 비용이 커질 수 있음 | 설계와 도구 난도가 높아 전 영역 적용은 부담이 큼 |
| 대표 환경 | 단위 테스트 실행 범위 확인 | 서비스 제어 흐름 검증 | 중요 계산·복합 조건 경로 검증 | 항공·제어 안전 로직의 MC/DC 검증 |

> 요약: 커버리지는 숫자 경쟁이 아니라 아직 테스트 밖에 남아 있는 구조 위험을 찾는 보조 지표임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 커버리지 기준 | 무엇을 커버한 것으로 볼지 기준을 정해 수치 해석을 일관되게 만듦 |
| 실행 계측 | 코드 실행 정보를 수집해 실제 테스트 통과 경로를 측정함 |
| 공백 분석 | 실행되지 않은 구문과 분기와 조건을 찾아 보완 대상을 정함 |
| 위험 기반 목표 | 모듈 중요도에 따라 서로 다른 커버리지 목표를 적용해 비용을 통제함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기준 선택      | --> | 계측/실행      | --> | 공백 분석      | --> | 테스트 보강    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기준 선택**: 모듈 위험도에 맞는 커버리지 수준을 정함
2. **계측 및 실행**: 도구로 실행 경로를 측정함
3. **공백 분석**: 미실행 분기와 조건을 확인함
4. **테스트 보강**: 공백을 줄이는 케이스를 추가함

## Ⅵ. 실무 적용 및 유의점

1. 일반 서비스 개발에서는 커버리지 수치가 품질 그 자체로 오해되기 쉬우므로 변이 테스트나 결함 지표와 함께 보고 분기 커버리지와 운영 유출 결함 비율로 확인함
2. 안전성 높은 제어 모듈에서는 강한 기준이 필요하지만 모든 코드에 MC/DC를 적용하면 비용이 과도하므로 중요 경로에 한정 적용하고 중요 경로 커버리지와 테스트 설계 시간으로 확인함

## Ⅶ. 결론

테스트 커버리지는 테스트가 얼마나 많은지보다 어떤 구조 위험이 아직 비어 있는지를 보여주는 지표로 써야 함.
