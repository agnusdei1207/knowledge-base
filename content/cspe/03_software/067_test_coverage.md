## 미리 알고가기

- 테스트 커버리지는 테스트가 코드 구조를 얼마나 실행했는지 나타내는 지표임
- 구문과 분기와 조건과 경로와 MC/DC는 점점 강한 검증 수준을 가짐
- 높은 커버리지가 높은 품질을 자동 보장하지는 않음

## Ⅰ. 개요

- **정의/개념**: 테스트 커버리지는 작성된 테스트가 코드의 구문과 분기와 조건과 실행 경로를 어느 정도 실행했는지 정량화하는 구조 기반 검증 지표 체계임
- **배경/필요성**: 테스트 수만 많아도 실제로 중요한 분기와 조건이 실행되지 않을 수 있으므로, 구조 관점에서 검증 공백을 확인할 기준이 필요함

## Ⅱ. 특징

- 구문 커버리지는 가장 기본적이지만 분기 누락을 놓칠 수 있음
- 분기와 조건과 경로 커버리지는 검증 강도는 높지만 비용도 증가함
- MC/DC는 안전성 높은 분야에서 조건 독립성을 확인하는 강한 기준임
- 수치 목표만 따라가면 의미 없는 테스트가 늘어날 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 구문 | 분기 | 조건 | 경로 | MC/DC |
|:---|:---|:---|:---|:---|:---|
| 검증 대상 | 문장 실행 | 분기 참/거짓 | 개별 조건 값 | 가능한 실행 경로 | 조건 독립 영향 |
| 장점 | 측정 쉬움 | 분기 누락 감소 | 복합 조건 확인 | 강한 구조 검증 | 안전성 검증 강함 |
| 한계 | 얕은 검증 | 복합 조건 한계 | 조합 폭 증가 | 폭발적 증가 | 설계와 도구 난도 큼 |
| 적합 환경 | 일반 단위 테스트 | 일반 품질 관리 | 조건 많은 로직 | 제한적 핵심 로직 | 항공·안전 critical |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Coverage Metric Definition | 무엇을 커버한 것으로 볼지 기준을 정해 수치 해석 일관성을 만든다 |
| Instrumentation | 코드 실행 정보를 수집해 실제 테스트 통과 경로를 측정함 |
| Gap Analysis | 실행되지 않은 구문과 분기를 찾아 보완 대상 위험을 식별함 |
| Risk-based Target | 모듈 중요도에 따라 커버리지 목표를 다르게 적용해 과도한 비용을 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기준 선택      | --> | 계측/실행      | --> | 공백 분석      | --> | 테스트 보강    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기준 선택**: 모듈 위험도에 맞는 커버리지 수준을 정함
2. **계측 및 실행**: 도구로 실행 경로를 측정함
3. **공백 분석**: 미실행 분기와 조건을 확인함
4. **테스트 보강**: 공백을 줄이는 케이스를 추가함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 커버리지 수치를 목표화하면 의미 없는 테스트를 늘려 숫자만 올리는 왜곡이 생길 수 있음
   - 해결방안: 결함 탐지력과 함께 평가하고 coverage-value ratio와 mutation score로 검증함
2. 문제: 경로 커버리지나 MC/DC를 모든 모듈에 적용하면 비용이 과도하게 증가할 수 있음
   - 해결방안: 위험 기반 목표를 적용하고 test design effort와 critical path coverage로 검증함
3. 문제: 커버리지가 높아도 외부 요구 미스매치나 데이터 품질 문제는 여전히 놓칠 수 있음
   - 해결방안: 블랙박스 테스트와 병행하고 defect escape rate와 requirement coverage로 검증함

## Ⅶ. 적용 사례

- 금융 계산 로직에서는 분기 커버리지를 강화하고 확인 지표는 critical path coverage와 defect escape rate임
- 안전성 높은 제어 모듈에서는 MC/DC를 적용하고 확인 지표는 mutation score와 test design effort임
- 일반 서비스팀에서는 커버리지와 요구 검증을 함께 보고 확인 지표는 coverage-value ratio와 requirement coverage임

## Ⅷ. 결론

테스트 커버리지는 숫자 경쟁이 아니라 어떤 구조 위험이 아직 테스트 밖에 남아 있는지 보여주는 보조 지표로 써야 함.
