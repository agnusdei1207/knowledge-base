## 미리 알고가기

- 캐시 계층은 자주 읽는 데이터를 메모리에 잠시 두어 원본 저장소 접근을 줄이는 구조임
- TTL은 캐시가 자동으로 만료되는 시간을 뜻함
- 캐시 스탬피드는 인기 데이터가 한꺼번에 만료돼 원본 저장소로 요청이 몰리는 현상임

## Ⅰ. 개요

- **정의/개념**: 캐시 계층은 데이터베이스나 외부 서비스에 반복적으로 접근하는 대신 자주 사용되는 결과를 메모리 기반 저장소에 임시 보관해 응답 지연과 원본 부하를 줄이는 성능 최적화 계층임.
- **배경/필요성**: 트래픽이 늘어날수록 모든 조회를 원본 저장소로 보내면 지연과 비용이 함께 커지므로, 접근 빈도가 높은 데이터를 빠르게 재사용할 중간 계층이 필요함.

## Ⅱ. 특징

- 응답 시간을 줄이고 원본 저장소 부하를 낮출 수 있음
- Redis는 자료구조와 부가 기능이 풍부하고, Memcached는 단순 캐시에 가볍게 쓰기 좋음
- 키 설계와 TTL과 무효화 규칙이 캐시 품질을 좌우함
- 캐시 장애나 동시 만료를 대비하지 않으면 성능 최적화 계층이 전체 장애의 시작점이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Redis | Memcached |
|:---|:---|:---|
| 제공 기능 | 문자열과 목록과 집합 등 다양한 자료구조를 제공함 | 단순 키-값 캐시에 집중함 |
| 강점 | 세션과 랭킹과 분산 락 같은 확장 활용이 가능함 | 구조가 단순하고 오버헤드가 낮음 |
| 한계 | 기능이 많은 만큼 운영 설정이 복잡해질 수 있음 | 자료구조와 부가 기능이 제한적임 |
| 잘 맞는 용도 | 캐시 외에 세션과 이벤트 처리까지 필요한 환경 | 단순 조회 결과를 빠르게 보관하는 환경 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 캐시 키 설계 | 어떤 단위로 재사용할지 정해 적중률과 무효화 정확도를 좌우함 |
| 만료와 무효화 정책 | TTL과 수동 삭제 규칙으로 데이터 신선도와 적중률의 균형을 맞춤 |
| 적재 방식 | 캐시 우회 조회나 쓰기 동시 반영 같은 방식이 일관성 특성을 결정함 |
| 보호와 우회 절차 | 동시 만료 방지와 원본 우회 경로를 두어 장애 전파를 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요청 수신      | --> | 캐시 조회      | --> | 미적중 시 원본 조회 | --> | 캐시 적재/만료  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요청 수신**: 애플리케이션이 데이터를 요청함
2. **캐시 조회**: 키 기준으로 캐시 적중 여부를 확인함
3. **미적중 시 원본 조회**: 값이 없으면 원본 저장소에서 읽음
4. **캐시 적재와 만료**: 결과를 저장하고 만료 정책을 적용함

## Ⅵ. 실무 적용 및 유의점

1. 상품 상세와 목록 조회처럼 반복 접근이 많은 화면에서는 캐시가 효과적이지만 TTL과 무효화 규칙이 틀리면 오래된 데이터가 노출되므로 적중률과 오래된 데이터 노출 건수로 확인함.
2. 이벤트와 인기 상품처럼 특정 키에 요청이 몰리는 환경에서는 동시 만료가 원본 장애로 번질 수 있으므로 만료 시간 분산과 요청 합치기를 적용하고 스탬피드 발생 건수와 원본 급증 비율로 확인함.

## Ⅶ. 결론

캐시 계층의 성능 효과는 메모리에 값을 두는 것만으로 끝나지 않고 데이터 신선도와 장애 전파를 함께 통제할 때 완성됨.
