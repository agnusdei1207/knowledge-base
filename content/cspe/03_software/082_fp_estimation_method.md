# 📖 【암기용】 개념 완전 이해

> 목적: FP 간이법과 정통법을 요구사항 상세도에 따라 선택하는 기준으로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.
> FP의 5개 기능유형(EI/EO/EQ/ILF/EIF)과 DET/RET/FTR 정의 자체는 081_function_point.md에서 다뤘으므로 여기서는 반복하지 않는다. 이 파일은 "그 판정을 언제, 어느 정도 정밀하게 할 것인가"를 다룬다.

## 한눈에
- **개요**: 간이법·정통법은 **기능점수(FP) 산정 방법**을 요구사항의 상세도에 맞춰 정밀도를 달리 적용하는 두 가지 방식임 — 간이법은 복잡도 판정 없이 빠르게, 정통법은 DET·RET·FTR로 정밀하게 산정함
- **왜 필요한가**: 기획 초기 단계는 상세 화면 설계서가 없어 DET·RET·FTR을 셀 수 없고, 반대로 계약·검수 단계에서 간이법처럼 대충 산정하면 대가 분쟁의 근거가 부족해짐. 사업 단계에 맞는 산정 정밀도를 골라야 함
- **핵심 직관**: 집을 지을 때 처음에는 평면도 면적만으로 예산 범위를 잡고(간이법), 착공 전 계약서에는 자재 하나하나의 수량과 규격까지 세어 넣는(정통법) 차이와 같음

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 기능점수 산정 방법 | FP를 구하는 절차의 정밀도 수준을 정하는 방식 — 간이법·정통법이 속하는 **상위 개념**(081의 FP 자체가 더 상위) | 견적을 "눈대중"으로 낼지 "실측"으로 낼지 정하는 것 |
| 간이법 | 기능유형별 복잡도를 개별 판정하지 않고, 모든 기능에 '보통(Average)' 복잡도의 표준 가중치를 일괄 적용해 빠르게 추정하는 방법 | 방 개수만 세어 이사 견적을 대략 내는 것 |
| 정통법 | 081에서 다룬 DET·RET·FTR을 기능 하나하나 판정해 낮음/보통/높음 복잡도와 정확한 가중치를 적용하는 방법 | 짐 하나하나의 무게와 부피를 재서 정밀 견적을 내는 것 |
| 기준선 FP(Baseline FP) | 요구사항 분석이 끝난 시점에 발주자·수행사가 공식 승인한 FP 값 — 이후 계약·대가 산정의 기준이 됨 | 공사 계약서에 도장 찍은 확정 설계도 |
| 변경 FP | 기준선 확정 이후 추가·변경된 요구사항만 별도로 산정한 FP | 계약 이후 추가된 공사 항목의 추가 견적 |

## 깊이 이해

### 간이법 계산법 — 081의 '보통' 가중치를 그대로 쓴다
- 간이법은 복잡도를 낮음/보통/높음으로 판정하는 절차(DET·RET·FTR 세기)를 생략하고, 081에서 본 표준 가중치표의 **보통(Average) 열만** 모든 기능에 일괄 적용한다: EI=4, EO=5, EQ=4, ILF=10, EIF=7.
- 예: RFP 단계에서 화면 목록만 보고 EI 20개, EO 8개, EQ 15개, ILF 5개, EIF 2개로 기능 개수만 파악했다고 하자. 간이법 UFP = 20×4 + 8×5 + 15×4 + 5×10 + 2×7 = 80+40+60+50+14 = 244점. DET·RET·FTR을 하나도 세지 않고도 몇 시간 안에 예산 범위를 잡을 수 있다.

### 정통법 계산법 — 기능마다 실제 복잡도를 판정한다
- 분석이 끝나 상세 화면설계서가 나오면, 같은 시스템의 기능 하나하나를 DET·RET·FTR로 판정해 낮음/보통/높음 가중치를 정확히 적용한다.
- 예: 위 시스템을 정통법으로 재산정했더니 EI 20개 중 12개는 보통(4점)이지만 8개는 필드가 많아 높음(6점)으로 판정되고, ILF 5개 중 2개는 하위그룹이 많아 높음(15점)으로 판정됐다고 하자. 정통법 UFP = (12×4+8×6) + 8×5 + 15×4 + (3×10+2×15) + 2×7 = (48+48) + 40 + 60 + (30+30) + 14 = 96+40+60+60+14 = 270점.
- 간이법(244점)과 정통법(270점)의 차이는 약 10.7%다. 이 정도 편차는 흔하며, 그래서 계약 대가 산정처럼 오차가 곧 금액 분쟁으로 이어지는 단계에서는 반드시 정통법으로 재확인해야 한다.

### 언제 어느 방법을 쓰는가 — 판별 원리
- 판별 기준은 하나다: "이 산정 결과가 계약·대가·검수의 법적 근거가 되는가?" 그렇다면 정통법, 아니라면(내부 예산 초안 수준이라면) 간이법으로 충분하다.
- 기획·RFP 단계(상세 설계서 없음, 화면 목록 수준) → 간이법으로 예산 범위(예: 200~280점)를 잡는다.
- 분석 완료·계약 체결·검수 단계(DET·RET·FTR을 셀 수 있는 상세 자료 있음) → 정통법으로 기준선 FP를 확정한다.
- 기준선 확정 이후 요구사항이 추가·변경되면, 기준선 FP를 건드리지 않고 변경분만 정통법으로 별도 산정해 변경 FP로 관리한다 — 그래야 원래 계약 범위와 추가 비용을 분리해 분쟁을 막을 수 있다.

### 흔한 오해
- 간이법을 "대충 세는 방법"으로 오해하기 쉽지만, 실제로는 요구사항이 아직 상세화되지 않은 시점에 공식적으로 인정되는 추정 절차다. 다만 이 값을 그대로 최종 계약 금액으로 고정하면 안 되고, 분석이 끝나는 대로 정통법으로 재산정해 기준선을 다시 승인받아야 한다.
- 정통법이 항상 "더 맞는 값"은 아니다. DET·RET·FTR 판정 자체도 산정자에 따라 편차(보통 15% 내외)가 생길 수 있으므로, 정통법도 산정자 2인의 교차 검토 같은 품질 관리가 필요하다.

## 연결 개념
- 081_function_point.md — 간이법·정통법이 공통으로 쓰는 FP 기능유형과 복잡도 가중치의 정의(선행 개념)
- SW 대가산정 — 기준선 FP·변경 FP에 단가를 곱해 계약 금액을 정하는 후속 절차
- 요구사항 기준선 — 정통법으로 전환하는 시점을 정하는 판단 근거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 간이법·정통법 문제는 계산식 암기가 아니라 사업 단계, 산정 근거, 재산정 통제를 연결해 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: FP 산정 방법은 요구사항 상세도에 따라 간이법과 정통법을 선택하는 규모 추정 체계이다.
> 2. **가치**: 초기 예산 편성에는 간이법, 계약·분석·검수에는 정통법을 적용해 산정 시간과 정확도 균형을 맞춘다.
> 3. **판단 포인트**: RFP, 분석 완료, 변경 승인 단계별로 산정 기준선을 분리하지 않으면 대가 분쟁이 발생한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산정 방법 선택 역량 확인 | 간이법·정통법 차이, 적용 시점, 입력 산출물 | 두 방법을 우열 관계로 단정하지 않음 |
| 공공 SW 계약 실무 이해 확인 | 기준선 FP, 변경 FP, 검수 FP | 최초 견적을 최종 계약 기준으로 고정하지 않음 |
| 산정 품질 통제 확인 | DET/RET/FTR, 산정자 편차, 재산정 트리거 | 화면 수만으로 정통법을 설명하지 않음 |
> 요약: 방법 선택은 요구사항 성숙도와 계약 단계에 맞춰 간이 추정에서 정밀 검증으로 전환하는 판단 문제이다.

## Ⅰ. 개요 및 필요성

- 개요: 기능점수 상세도 선택 절차
- 배경: 초기 기획에는 요구사항이 불완전해 정통법 적용 근거가 부족하고, 계약 이후에는 기능유형과 복잡도 근거가 필요하다.
- 필요성: 간이법은 예산 범위를 산정하고 정통법은 기능유형, DET, RET, FTR 근거로 기준선과 변경 대가를 확정한다.

## Ⅱ. 구조 및 구성요소

```text
사업 단계 -> 요구사항 상세도 판단 -> 산정 방법 선택
기획/RFP -> 간이법 -> 예산 범위 FP
분석/계약/검수 -> 정통법 -> 기준선 FP/변경 FP
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| 간이법 | 초기 기능량 추정 | 평균 복잡도, 기능목록, 화면·보고서 기준 |
| 정통법 | 기능유형별 정밀 산정 | EI·EO·EQ·ILF·EIF, DET/RET/FTR |
| 기준선 FP | 계약·일정 기준 | 분석 완료 시점 승인 |
| 변경 FP | 범위 변경 비용 산정 | 변경요청서와 승인 이력 |
> 요약: FP 산정 방법은 초기 추정, 기준선 확정, 변경 산정으로 분리해 적용해야 한다.

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 성숙도 평가 -> 간이법 1차 산정 -> 예산 범위 설정
-> 분석 산출물 확정 -> 정통법 재산정 -> 기준선 승인
-> 변경요청 발생 -> 변경 FP 산정 -> 계약·일정 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | RFP 기능목록 기반 간이 산정 | 기능목록 누락률 5% 이하 |
| 2 | 분석 단계 기능유형 재분류 | EI·EO·EQ·ILF·EIF 검토표 |
| 3 | DET/RET/FTR 복잡도 판정 | 산정 근거 첨부율 100% |
| 4 | 기준선 FP 승인 | 발주자·수행사 합의 기록 |
| 5 | 변경 FP 분리 산정 | 변경요청 처리기한 5영업일 |
> 요약: 간이법은 예산 범위, 정통법은 기준선과 변경 대가를 확정하는 순서로 동작한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RFP 단계는 간이법으로 예산 범위 FP를 산정하고 산정 편차 20% 범위를 계약 전 검토자료에 명시함.
2. 분석 완료 시 EI·EO·EQ·ILF·EIF와 DET·RET·FTR 근거를 포함한 정통법 산정표를 승인받음.
3. 기준선 승인 이후 추가·변경·삭제 기능은 변경 FP로 분리하고 비용·일정 영향도를 승인 프로세스에 연결함.

**결론 (2줄):**
- 기술사 판단: 요구사항 상세도가 낮으면 간이법, 계약·검수 책임이 있으면 정통법을 선택함.
- 향후 방향: FP 산정 도구는 요구사항 관리, 변경관리, 대가산정 산출서를 연결하는 통합 추적 체계로 발전함.
