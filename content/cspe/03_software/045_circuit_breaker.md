## Ⅰ. 개요
- 정의: 타 서비스 호출 실패 시 연쇄 장애(Cascading Failure) 방지를 위해 통신을 즉시 차단하는 패턴.
- 출제 의도: 분산 시스템의 결함 허용(Fault Tolerance)과 복원력 확보를 위한 상태 전이 메커니즘 이해 확인.

## Ⅱ. 구성요소
- ASCII 구조도
       (Success)         (Threshold Exceeded)
    +-----------+      +------------+
    |   Closed  | ---> |    Open    | (Fail Fast)
    +-----------+      +------------+
          ^                   |
          |    (Success)      v (Timeout)
          +----------- [ Half-Open ]
- 구성요소 표
| 상태 | 설명 | 비유 |
| :--- | :--- | :--- |
| Closed | 정상 상태, 모든 요청이 목적지 서비스로 전달됨 | 정상 회로 |
| Open | 장애 감지 상태, 요청을 즉시 거부하고 에러/Fallback 반환 | 차단된 두꺼비집 |
| Half-Open | 복구 시도 상태, 일부 요청만 보내 상태 호전 여부 확인 | 테스트 통전 |
> 요약: 장애 발생 시 기다리지 않고 빠르게 실패(Fail-fast) 처리하여 자원을 보호함.

## Ⅲ. 절차
- ASCII 흐름도
  [요청 감시] -> [실패율 계산] -> [상태 전이(Open)] -> [대체 로직 수행]
- 4단계 설명
1. 서비스 간 통신 시 발생하는 에러와 타임아웃 횟수를 지속적으로 카운트함.
2. 설정된 임계치(예: 50% 실패) 도달 시 상태를 Open으로 변경함.
3. Open 상태에서는 실제 호출 대신 미리 준비된 Fallback(기본값 등) 제공함.
4. 일정 시간 경과 후 Half-Open으로 전환하여 서비스 정상화 여부 판단함.
> 요약: 시스템 전체의 붕괴를 막기 위해 국지적 장애를 격리하는 프로세스임.

## Ⅳ. 문제점
- 설정 민감도: 임계치가 너무 낮으면 잦은 차단, 너무 높으면 연쇄 장애 방어 실패함.
- 데이터 누락: 차단 기간 동안 발생하는 요청에 대한 데이터 손실 또는 처리 지연 발생함.

## Ⅴ. 개선방안
- 동적 임계치: 트래픽 패턴에 따라 차단 임계치를 자동으로 조정하는 알고리즘 적용함.
- 메시지 큐 활용: 차단 시 요청을 큐에 적재하여 복구 후 순차적으로 처리(Buffering)함.

## Ⅵ. 전망
- 서비스 메쉬(Istio 등)의 기본 기능으로 내재화되어 별도 코드 구현 없이 인프라 설정으로 자동화됨.
- AI 기반 장애 예측 기술과 결합하여 장애 발생 전 선제적으로 차단기를 작동시키는 모델 연구됨.
- 클라우드 가용 영역(AZ) 단위의 서킷 브레이킹을 통해 광역 장애 대응 체계 구축의 핵심 도구로 활용됨.
