# 📖 【암기용】 개념 완전 이해

> 목적: 하이브리드 클라우드를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 하이브리드 클라우드는 **클라우드 배포 모델**의 한 유형으로, **온프레미스**(자체 데이터센터) 또는 **프라이빗 클라우드**와 **퍼블릭 클라우드**를 네트워크로 연결해 하나의 서비스처럼 운영하는 구조다.
- **왜 필요한가**: 레거시 시스템·민감 데이터는 한 번에 옮기기 어렵고 내부에 남겨야 하는 경우가 많아, 점진적 전환과 부분 확장이 필요하다.
- **핵심 직관**: 내부 금고에 핵심 장부를 두고, 대외 창구와 피크 업무 처리는 퍼블릭 클라우드에서 처리하는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 클라우드 배포 모델 | 퍼블릭·프라이빗·하이브리드·멀티 클라우드처럼 클라우드를 어떻게 구성해 쓰는지의 상위 분류 | 집을 자가·전세·월세 중 어떻게 소유·운영할지의 큰 틀 |
| 온프레미스 | 회사가 직접 소유·운영하는 물리 데이터센터 — 하이브리드의 '내부' 축 | 자가 소유 건물 |
| 프라이빗 클라우드 | 특정 조직 전용으로 격리된 클라우드 인프라(자체 구축 또는 CSP 전용 리전) | 회원 전용 클럽 |
| 퍼블릭 클라우드 | AWS·Azure 등 CSP가 여러 고객에게 공유 제공하는 클라우드 — 하이브리드의 '외부' 축 | 공유 오피스 |
| 전용회선(Direct Connect류) | 인터넷을 거치지 않고 CSP와 사내망을 물리적으로 직결하는 회선 | 전용 도로 |
| VPN | 인터넷 위에 암호화 터널을 만들어 사내망과 클라우드를 연결하는 방식 | 공용 도로 위의 방탄 차량 |
| IAM Federation | 사내 인증 체계(AD 등)와 클라우드 IAM을 연동해 SSO로 통합하는 것 | 사원증 하나로 본사와 클라우드를 모두 출입 |
| CDC(Change Data Capture) | DB의 변경분만 실시간으로 감지해 다른 시스템에 복제하는 기술 | 통장 거래 내역만 실시간 문자로 전달 |
| RPO / RTO | 데이터 손실 허용 범위(RPO)와 서비스 복구 목표 시간(RTO) | RPO=되돌아가도 되는 최대 시점, RTO=복구까지 걸려도 되는 최대 시간 |
| Zero Trust | "내부망이니까 안전하다"는 가정을 버리고 모든 접근을 매번 검증하는 보안 모델 | 사내에서도 매번 신분증을 다시 확인 |

## 깊이 이해

### 왜 한 번에 다 옮기지 못하나 — 이전 부담을 수치로
- 예: 20년 넘게 누적된 배치·연계 인터페이스가 수백 개인 ERP·메인프레임을 통째로 재작성하면 개발 기간이 1~2년, 실패 시 매출 영향이 막대하다. 반면 신규 기능(모바일 API)만 먼저 퍼블릭 클라우드에 올리고 기존 ERP는 내부에 남기면, 리스크를 분산하며 3~6개월 단위로 점진 전환할 수 있다.

### 연결 계층 설계 — 지연시간과 이중화
- 전용회선 지연시간은 보통 수 ms~수십 ms 수준으로 안정적이지만, 단일 회선 장애 시 전체가 끊기므로 전용회선+VPN 백업으로 이중화하고 BGP로 자동 경로 전환한다.
- 목표 수치 예: p95 지연 100ms 이하, 회선 가용성 99.9%(연간 다운타임 약 8.76시간 이하)가 실무 기준이다.

### 데이터 동기화 — CDC와 RPO
- 워크드 예: 모바일 주문 API(퍼블릭 클라우드)에서 발생한 주문을 내부 ERP(온프레미스) DB에 반영해야 한다면, 매 1시간마다 배치로 옮기는 방식은 RPO가 최대 1시간이 되어 장애 시 최대 1시간치 데이터 유실 위험이 있다. CDC로 변경 즉시(수 초~수 분 이내) 전달하면 RPO를 15분 이하로 줄일 수 있다.

### 흔한 오해
- "VPN이나 전용회선만 연결하면 하이브리드 클라우드"라는 오해가 흔하다. 실제로는 인증 통합(IAM Federation), 네트워크 세그먼트 분리, 데이터 흐름 정의, 회선 장애 시 우회 경로까지 설계해야 완성된 하이브리드 아키텍처다.

## 연결 개념
- 클라우드 배포 모델 — 하이브리드는 배포 모델 중 온프레미스 연계 형태
- 클라우드 마이그레이션 6R — 이전 과정에서 하이브리드가 중간 상태가 됨
- 멀티 클라우드 전략 — 하이브리드와 다중 CSP가 함께 구성될 수 있는 다른 축

> 2. **가치**: 민감 데이터와 레거시 업무는 내부에 두고, 대외 채널·분석·피크 용량은 퍼블릭 클라우드로 확장한다.

## Ⅰ. 개요 및 필요성

- 개요: 하이브리드 클라우드는 온프레미스와 퍼블릭 클라우드 통합 모델임.
- 배경: 기업은 민감 데이터 보호, 레거시 연계, 단계적 이전, 피크 부하 대응을 동시에 요구한다.
- 필요성: 전용회선, IAM, 보안정책, 데이터 동기화, 관측성 기준을 통합해 양 환경을 운영한다.

---

## Ⅱ. 구조 및 구성요소

```text
User -> Public Cloud App/API -> Hybrid Network -> On-Prem DB/ERP
                         +-> IAM Federation
                         +-> Logging/Monitoring/SIEM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 퍼블릭 클라우드 영역 | 웹, API, 분석, 피크 처리 | 오토스케일링, CDN, 관리형 DB |
| 온프레미스 영역 | 민감 데이터, 레거시, ERP | 내부망, 기존 인증, 전용 DB |
| 연결 계층 | VPN, 전용 회선, 라우팅 | 이중화, QoS, DNS |
| 통합 운영 | IAM, 로그, 모니터링, 정책 | SSO, SIEM, CSPM |

> 요약: 하이브리드는 애플리케이션, 내부 시스템, 연결 계층, 운영 통제를 하나의 장애 도메인처럼 관리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 요청 -> 클라우드 API 처리 -> 내부 데이터 조회/동기화
-> 결과 반환 -> 로그 수집 -> 회선/지연/RPO 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 요청을 클라우드 프런트로 수신 | WAF, CDN, 인증 |
| 2 | 필요한 내부 데이터 호출 | p95 지연 100ms 이하 |
| 3 | 트랜잭션 또는 이벤트 동기화 | RPO 15분 이하, 중복 처리 방지 |
| 4 | 로그·보안 이벤트 통합 | SIEM 수집률 95% 이상 |

> 요약: 하이브리드 흐름은 클라우드 처리와 내부 데이터 접근 사이의 지연·정합성·보안 통제를 검증해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 업무 분리: 민감 DB와 ERP는 온프레미스, 웹·API·분석은 퍼블릭에 배치하고 데이터 흐름을 API/이벤트 단위로 제한
2. 연결 통제: 전용 회선 2개, VPN 백업, BGP 라우팅, DNS 장애 전환 절차로 회선 장애 영향을 줄임
3. 운영 통합: SSO, 중앙 로그, CDC 모니터링, RTO/RPO 대시보드를 구축하고 반기 DR 훈련 수행

**결론 (2줄):**
- 기술사 판단: 민감 데이터·레거시 의존과 클라우드 확장 요구가 공존하면 하이브리드를 선택하고, 신규 독립 서비스는 퍼블릭 우선으로 설계함
- 향후 방향: 하이브리드는 엣지, 소버린 클라우드, 쿠버네티스 공통 운영과 결합해 점진 이전 플랫폼으로 발전함
