## 미리 알고가기

- 전용 환경은 프라이빗 클라우드와 기존 데이터센터처럼 조직이 직접 통제하는 실행 환경임
- 하이브리드 클라우드는 전용 환경과 퍼블릭 클라우드를 연결해 하나의 업무를 구성함
- 워크로드 배치는 데이터 규제·응답 지연·자원 변동에 따라 실행 환경을 선택함
- 클라우드 버스팅은 기본 부하를 전용 환경에서 처리하고 초과 부하를 퍼블릭으로 확장함
- 통합 ID는 사용자·서비스 계정을 환경 간 연동하고 같은 접근 정책을 적용함
- 데이터 동기화는 환경별 사본의 변경 순서와 일관성 수준을 관리함
- 경계 지연은 전용 환경과 퍼블릭 클라우드 사이의 왕복 시간과 전송 대역폭에 좌우됨

## 작성 근거(검토용)

- 하이브리드는 두 환경의 존재보다 업무·데이터 배치와 경계 연결이 핵심이므로 이를 중심으로 전개함
- 멀티 클라우드와 결합 환경·업무 배치·데이터 경로를 같은 수준에서 비교하고 통제 기준·적합 조건은 Ⅳ 구성요소와 결론에서 다룸
- Ⅴ절은 업무 분류부터 환경 배치·경계 연결·데이터 연계·운영 검증까지의 적용 절차로 구성함
- 제목부터 결론까지 5회 전수 검수하여 환경 결합의 이점과 경계 비용을 함께 확인함

## Ⅰ. 개요

- **정의/개념**: 하이브리드 클라우드는 조직 전용 환경과 퍼블릭 클라우드를 연결하고 업무·데이터를 요구 조건에 따라 나누어 배치하는 구조임
- **배경/필요성**: 기존 시스템과 규제 데이터를 유지하면서 퍼블릭 자원을 사용하기 위해 환경 간 연결·배치 기준이 필요함

### 쉽게 이해하기 (학습용)
- 하이브리드 클라우드는 기존 전용 환경을 유지하면서 퍼블릭 자원의 장점을 연결해 쓰는 구조임

## Ⅱ. 특징

- 규제 데이터와 기존 시스템은 전용 환경에 두고 탄력 업무는 퍼블릭에 배치할 수 있음
- 네트워크·DNS·ID·인증서를 연동해야 하나의 서비스 경로로 동작함
- 환경 간 호출은 지연·대역폭·데이터 전송 비용과 장애 전파 경로를 추가함
- 데이터 복제·동기화 방식과 일관성 수준이 장애 전환 시점과 결과 차이를 결정함

### 쉽게 이해하기 (학습용)
- 두 환경을 연결하면 네트워크 지연과 데이터 사본의 차이까지 하나의 서비스 문제로 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 하이브리드 클라우드 | 멀티 클라우드 |
|:---|:---|:---|
| 결합 환경 | 전용 환경과 퍼블릭 클라우드를 연결해 기존 자산·규제 데이터를 유지 | 둘 이상의 퍼블릭 클라우드를 병행해 공급자별 서비스를 선택 |
| 업무 배치 | 데이터·계층을 환경 경계로 분리 | 업무·서비스를 공급자 경계로 분리 또는 중복 |
| 데이터 경로 | 전용망·VPN으로 전용 환경과 데이터를 교환 | 공급자 간 복제·API·데이터 전송 경로 사용 |

> 요약: 하이브리드는 전용 환경과 퍼블릭의 결합이고 멀티 클라우드는 퍼블릭 공급자 간 업무 배치·복제임.

### 쉽게 이해하기 (학습용)
- 하이브리드는 기존 환경과 퍼블릭의 연결, 멀티 클라우드는 여러 공급자 활용에 초점을 둠

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 전용 환경 | 기존 애플리케이션·규제 데이터·전용 장비를 운영함 |
| 퍼블릭 환경 | 탄력 컴퓨팅·관리 서비스·외부 접점을 제공함 |
| 연결 계층 | 전용 회선·VPN·DNS로 서비스 경로를 연결함 |
| 통합 ID·키 관리 | 사용자·서비스 계정과 인증서·암호키 정책을 연동함 |
| 데이터 연계 | API·메시지·복제로 변경 데이터와 처리 결과를 교환함 |
| 통합 운영 | 배포·로그·추적·비용 정보를 환경 공통 식별자로 연결함 |

```text
사용자 -> 퍼블릭 API -> 전용 환경 서비스 -> 전용 데이터
              |                 |
         통합 관측 <------- 통합 ID·정책
```

> 요약: 퍼블릭 접점과 전용 데이터 사이의 연결·ID·데이터 경로가 하이브리드 서비스 경계를 형성함.

### 쉽게 이해하기 (학습용)
- 전용 환경과 퍼블릭 사이에 안전한 통신로·공통 신원·데이터 이동 규칙이 필요함

## Ⅴ. 원리 및 절차 흐름도

```text
업무·데이터 분류 -> 환경별 배치 -> 경계 연결 -> ID·데이터 연계 -> 성능·복구 검증
```

1. 규제·지연·장비 의존성·부하 변동을 업무와 데이터별로 분류함
2. 전용 환경에 남길 대상과 퍼블릭으로 배치할 대상을 정함
3. 전용 회선·VPN·DNS·인증서로 환경 간 서비스 경로를 구성함
4. 통합 ID와 API·메시지·복제로 권한과 데이터를 연계함
5. 경계 지연·전송량·일관성·장애 전환 시간을 측정해 배치를 조정함

> 요약: 규제와 성능 요구로 환경을 나누고 연결·동기화·복구 결과로 구성을 검증함.

### 쉽게 이해하기 (학습용)
- 남겨 둘 업무와 옮길 업무를 나눈 뒤 두 장소의 길과 출입증, 자료 전달 방식을 맞춤

## Ⅵ. 실무 사례

1. 고객 DB는 전용 환경에 두고 API를 퍼블릭에 배치해 왕복 지연·전송량을 확인함
2. 배치 서버는 클라우드 버스팅으로 초과 작업을 퍼블릭으로 확장하고 대기 시간·데이터 전송 비용을 확인함

### 쉽게 이해하기 (학습용)
- 민감 데이터는 전용 환경에 두고 변동 부하는 퍼블릭에서 처리하되 경계 비용을 측정함

## Ⅶ. 결론

- 하이브리드 클라우드는 전용 환경 유지 조건·경계 지연·데이터 일관성·환경 간 운영 비용을 기준으로 선택해야 함

### 쉽게 이해하기 (학습용)
- 두 환경을 연결할 수 있다는 사실보다 연결 후 성능·일관성·운영 부담을 감당할 수 있는지가 중요함
