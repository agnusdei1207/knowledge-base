# 📖 【암기용】 개념 완전 이해

> 목적: 하이브리드 클라우드를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 온프레미스 또는 프라이빗 클라우드와 퍼블릭 클라우드를 연결해 하나의 서비스처럼 운영하는 구조
- **왜 필요한가**: 모든 시스템을 한 번에 퍼블릭 클라우드로 이전하기 어렵고, 민감 데이터와 레거시 시스템은 내부에 남겨야 하는 경우가 많다.
- **핵심 직관**: 내부 금고에 핵심 장부를 두고, 대외 창구와 피크 업무 처리는 퍼블릭 클라우드에서 처리하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 기업 시스템은 메인프레임, ERP, DB, 사내망, 인증 체계와 얽혀 있다. 클라우드 전환은 한 번의 이사가 아니라 연결·분리·점진 이전의 과정이다.
- **작동 원리**: 내부 시스템과 퍼블릭 클라우드를 VPN 또는 전용 회선으로 연결하고, IAM, DNS, 모니터링, 데이터 동기화, 보안 정책을 통합한다. 업무별로 내부 처리와 클라우드 처리를 나눈다.
- **비유**: 병원 본원에는 환자 원장을 보관하고, 예약·문진·알림 서비스는 외부 클라우드에서 운영하되 전용 통로로 필요한 데이터만 주고받는 구조다.
- **구체 예시**: ERP DB는 사내 DB에 두고, 모바일 주문 API는 퍼블릭 클라우드 Kubernetes에 배포한다. 주문 확정 데이터만 메시지 큐로 내부 ERP에 전달한다.
- **흔한 오해·주의점**: 회선만 연결하면 하이브리드 클라우드가 아니다. 인증, 네트워크 세그먼트, 데이터 흐름, 장애 시 우회 경로가 설계되어야 한다.

## 연결 개념
- 클라우드 배포 모델 - 하이브리드는 배포 모델 중 온프레미스 연계 형태
- 클라우드 마이그레이션 6R - 이전 단계에서 하이브리드가 중간 상태가 됨
- 멀티 클라우드 전략 - 하이브리드와 다중 CSP가 함께 구성될 수 있음

> 2. **가치**: 민감 데이터와 레거시 업무는 내부에 두고, 대외 채널·분석·피크 용량은 퍼블릭 클라우드로 확장한다.
> 3. **판단 포인트**: 지연시간, 데이터 이동량, 회선 이중화, IAM 연동, 장애 전환 절차가 성패를 결정한다.

## Ⅰ. 개요 및 필요성

하이브리드 클라우드는 온프레미스와 퍼블릭 클라우드를 통합 운영하는 배포 모델이다. 기업은 민감 데이터 보호, 레거시 연계, 단계적 이전, 피크 부하 대응을 동시에 요구한다. 따라서 네트워크 연결뿐 아니라 인증, 보안, 데이터 동기화, 관측성 통합이 필요하다.

---

## Ⅱ. 구조 및 구성요소

```text
User -> Public Cloud App/API -> Hybrid Network -> On-Prem DB/ERP
                         +-> IAM Federation
                         +-> Logging/Monitoring/SIEM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 퍼블릭 클라우드 영역 | 웹, API, 분석, 피크 처리 | 오토스케일링, CDN, 관리형 DB |
| 온프레미스 영역 | 민감 데이터, 레거시, ERP | 내부망, 기존 인증, 전용 DB |
| 연결 계층 | VPN, 전용 회선, 라우팅 | 이중화, QoS, DNS |
| 통합 운영 | IAM, 로그, 모니터링, 정책 | SSO, SIEM, CSPM |

> 요약: 하이브리드는 애플리케이션, 내부 시스템, 연결 계층, 운영 통제를 하나의 장애 도메인처럼 관리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 요청 -> 클라우드 API 처리 -> 내부 데이터 조회/동기화
-> 결과 반환 -> 로그 수집 -> 회선/지연/RPO 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 요청을 클라우드 프런트로 수신 | WAF, CDN, 인증 |
| 2 | 필요한 내부 데이터 호출 | p95 지연 100ms 이하 |
| 3 | 트랜잭션 또는 이벤트 동기화 | RPO 15분 이하, 중복 처리 방지 |
| 4 | 로그·보안 이벤트 통합 | SIEM 수집률 95% 이상 |

> 요약: 하이브리드 흐름은 클라우드 처리와 내부 데이터 접근 사이의 지연·정합성·보안 통제를 검증해야 한다.

## Ⅳ. 특징

| 구분 | 순수 퍼블릭 전환 | 하이브리드 클라우드 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 데이터 위치 | 퍼블릭 리전 중심 | 민감 데이터 내부 유지 | 데이터 반출 정책 충족 |
| 레거시 연계 | 전면 이전 필요 | API, 메시지, DB 복제로 연계 | 이전 기간 6~18개월 분산 |
| 지연시간 | 리전 내부 지연 중심 | 회선 지연 포함 | p95 100ms 이하 목표 |
| 장애 대응 | 클라우드 리전 DR | 회선·내부·클라우드 모두 고려 | RTO 1시간, RPO 15분 |

> 요약: 하이브리드는 단계적 전환과 데이터 위치 통제에 유리하지만 연결 지연과 장애 경로를 별도로 설계해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 업무 분리: 민감 DB와 ERP는 온프레미스, 웹·API·분석은 퍼블릭에 배치하고 데이터 흐름을 API/이벤트 단위로 제한
2. 연결 통제: 전용 회선 2개, VPN 백업, BGP 라우팅, DNS 장애 전환 절차로 회선 장애 영향을 줄임
3. 운영 통합: SSO, 중앙 로그, CDC 모니터링, RTO/RPO 대시보드를 구축하고 반기 DR 훈련 수행

**결론 (2줄):**
- 기술사 판단: 민감 데이터·레거시 의존과 클라우드 확장 요구가 공존하면 하이브리드를 선택하고, 신규 독립 서비스는 퍼블릭 우선으로 설계함
- 향후 방향: 하이브리드는 엣지, 소버린 클라우드, 쿠버네티스 공통 운영과 결합해 점진 이전 플랫폼으로 발전함
