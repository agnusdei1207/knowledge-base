## Ⅰ. 개요
- 정의: CPU·메모리·네트워크·스토리지 자원을 논리적 단위로 추상화하여 분할·통합·할당하는 기술임
- 배경: 서버 자원 낭비 해소 및 인프라의 민첩성/유연성 확보 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 서버 가상화 | 하이퍼바이저, 컨테이너 | 매우높음 |
| NW/스토리지 | SDN/NFV, SDS | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ VM 1 ]  [ VM 2 ]  [ VM 3 ]
  +--------------------------+
  |    하이퍼바이저 (VMM)      |
  +--------------------------+
  |      물리적 서버 (HW)      |

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 서버 가상화 | 한 대의 물리 서버를 여러 대의 가상 서버로 분할 | 아파트 세대 분할 |
| 네트워크 가상화 | 하드웨어 종속성 없는 소프트웨어 정의 네트워크 | 가상 사설망 |
| 스토리지 가상화 | 파편화된 저장 장치를 하나의 거대한 풀로 통합 | 외장하드 결합 |

> 요약: 하이퍼바이저와 가상화 계층으로 물리 자원을 논리 자원 풀과 격리된 실행 단위로 제공함

## Ⅲ. 절차
- ASCII 흐름도
  [자원 분석] -> [가상화 계층 구축] -> [자원 할당] -> [동적 관리]
    (HW 파악)       (Hypervisor)       (VM 생성)        (V-Motion)

- 4단계 설명
1. 현황조사: 기존 인프라의 CPU, 메모리, 스토리지 사용량을 실시간 측정함
2. 환경설정: 하이퍼바이저를 설치하거나 컨테이너 엔진을 구성함
3. 프로비저닝: 서비스 규모에 맞춰 필요한 자원을 논리적으로 쪼개어 할당함
4. 모니터링: 부하에 따라 가상 머신을 이동시키거나 자원을 증설(Scaling)함

> 요약: 사용량을 기준으로 가상 자원을 할당하고 이동·확장·회수하여 물리 자원과 매핑함

## Ⅳ. 문제점
- 가상화 계층(Hypervisor) 오버헤드로 인한 물리 서버 대비 성능 저하 발생함
- 가상 머신이 급격히 늘어나는 'VM Sprawl' 현상으로 관리 복잡도 가중됨

## Ⅴ. 개선방안
- (단기) 경량화된 컨테이너 기술을 도입하여 오버헤드를 최소화하고 밀도 높임
- (중기) 통합 가상화 관리 도구(VMS)를 도입하여 자원 수명 주기를 자동화함
- (장기) 하드웨어 보조 가상화와 장치 직접 할당으로 가상화 계층의 처리 비용을 줄임

## Ⅵ. 전망
- 엣지 컴퓨팅 확산에 따라 저사양 기기에서도 구동되는 초경량 가상화 부각됨
- 하드웨어 가속기(GPU, NPU) 가상화 기술이 AI 서비스의 핵심 인프라가 될 것임
