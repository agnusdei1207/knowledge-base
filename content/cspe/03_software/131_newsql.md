## 미리 알고가기

- NewSQL은 SQL·ACID 트랜잭션을 유지하면서 키 범위 분할과 합의 복제로 수평 확장하는 분산 관계형 DB 계열임
- CockroachDB는 SQL을 키-값 범위로 변환하고 범위별 Raft 합의와 MVCC로 데이터를 복제함
- Spanner는 기본 키 범위의 Split을 Paxos로 복제하고 TrueTime 타임스탬프로 외부 일관성을 제공함
- HLC(Hybrid Logical Clock)는 물리 시각과 논리 순서를 결합하고 TrueTime은 현재 시각의 불확실성 구간을 제공함
- 여러 범위·Split을 갱신하는 트랜잭션은 복제 합의 외에 분산 커밋 조정이 필요함

## 작성 근거(검토용)

- NewSQL은 SQL·ACID와 키 범위 분할·합의 복제·MVCC·분산 커밋의 결합 구조로 설명함
- 비교표는 CockroachDB·Spanner의 분할 단위·시간 및 순서·적합 조건을 대비함
- 실무 사례는 다중 리전 트랜잭션의 커밋 지연·재시도율·핫 범위 요청 점유율로 검증함

## Ⅰ. 개요

- **정의/개념**: NewSQL은 관계형 스키마·SQL·ACID를 제공하면서 데이터를 키 범위로 자동 분할하고 합의 복제해 수평 확장하는 분산 SQL 데이터베이스 계열임
- **배경/필요성**: 여러 노드·리전의 데이터와 트랜잭션을 확장하면서도 응용의 SQL·관계·일관성 요구를 유지하기 위해 분산 관계형 저장·커밋 구조가 필요함

### 쉽게 이해하기 (학습용)
- 익숙한 SQL 장부를 여러 지점에 나누면서 합의로 하나의 거래처럼 처리하는 분산 데이터베이스임

## Ⅱ. 특징

- SQL 계층이 관계형 질의를 분산 키-값 연산으로 변환하고 여러 범위의 결과를 병합함
- 키 범위를 자동 분할·재배치하고 범위별 합의 그룹이 변경 순서와 복제본 커밋을 결정함
- MVCC 타임스탬프로 일관된 읽기와 동시 트랜잭션을 처리하며 여러 범위 쓰기는 분산 커밋을 수행함
- 교차 리전 합의 왕복·트랜잭션 경합·단조 키 핫스폿이 커밋 지연과 재시도를 증가시킬 수 있음

### 쉽게 이해하기 (학습용)
- 수평 확장과 ACID를 함께 제공하지만 지점 간 합의 왕복과 충돌 재시도 비용이 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | CockroachDB | Spanner |
|:---|:---|:---|
| 분할 단위 | 정렬된 키-값 Range를 자동 분할·병합 | 기본 키 범위의 Split을 부하·크기에 따라 분할 |
| 시간·순서 | HLC·MVCC로 타임스탬프와 직렬화 순서를 관리 | TrueTime·MVCC로 외부 일관성 순서를 보장 |
| 적합 조건 | 배포 통제와 PostgreSQL 호환이 필요한 분산 SQL | TrueTime 기반 전역 순서와 관리형 글로벌 DB가 필요한 업무 |

> 요약: CockroachDB는 Range·Raft·HLC를, Spanner는 Split·Paxos·TrueTime을 사용해 분산 SQL 트랜잭션을 처리함.

### 쉽게 이해하기 (학습용)
- CockroachDB는 Range·HLC, Spanner는 Split·TrueTime을 중심으로 전역 순서를 만듦

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SQL 게이트웨이 | SQL을 분석·최적화하고 분산 키-값 연산과 결과 병합 계획을 만듦 |
| 범위·Split 디렉터리 | 키가 속한 범위와 복제본·리더 위치를 조회함 |
| 트랜잭션 조정자 | 여러 범위의 읽기·쓰기 타임스탬프와 커밋·중단을 조정함 |
| 합의 복제 그룹 | Raft 또는 Paxos로 범위별 변경 순서와 복제본 커밋을 결정함 |
| MVCC 저장 엔진·시계 | 타임스탬프별 데이터 버전과 HLC·TrueTime 순서를 관리함 |

```text
애플리케이션 -> SQL 게이트웨이 -> Range·Split -> 합의 복제본
                              \-> 트랜잭션 조정자·MVCC
```

> 요약: SQL 게이트웨이가 질의를 Range·Split 연산으로 나누고 트랜잭션 조정자와 합의 그룹이 MVCC 커밋을 결정함.

### 쉽게 이해하기 (학습용)
- SQL 창구, 키 구간 안내표, 거래 조정자, 합의 사본과 시간별 저장소로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
SQL 요청 -> Range·Split 선택 -> 범위별 실행 -> 합의·분산 커밋 -> 결과 반환
```

1. **SQL 요청 수신**: 게이트웨이가 질의를 분석해 키-값 연산과 트랜잭션 범위를 정함
2. **Range·Split 선택**: 키 범위 디렉터리에서 대상 복제 그룹과 리더를 찾음
3. **범위별 실행**: 각 범위에서 MVCC 읽기·쓰기와 충돌 검사를 수행함
4. **합의·분산 커밋**: 범위별 합의 후 여러 범위 트랜잭션의 커밋 타임스탬프를 확정함
5. **결과 반환**: 커밋 결과 또는 재시도·중단 상태를 응용에 반환함

> 요약: 분산 SQL은 대상 Range·Split에서 MVCC 연산과 합의를 수행하고 여러 범위의 커밋 타임스탬프를 조정함.

### 쉽게 이해하기 (학습용)
- 질의를 담당 구간에 나눠 보내고 각 사본의 합의와 여러 구간 커밋을 조정함

## Ⅵ. 실무 사례

1. 다중 리전 주문 DB는 지역 단위 데이터 배치를 적용하고 교차 리전 트랜잭션 비율·p99 커밋 지연을 확인함
2. 계정 원장은 분산 키와 재시도 정책을 적용하고 핫 범위 요청 점유율·트랜잭션 재시도율을 확인함

### 쉽게 이해하기 (학습용)
- 다중 리전 주문에 적용하고 커밋 지연·재시도·핫 범위 요청 비율을 확인함

## Ⅶ. 결론

- NewSQL은 SQL 호환성·키 분포·리전 배치·합의 왕복과 분산 트랜잭션 재시도 비용을 기준으로 선택해야 함
- 단일 DB 한계를 수치로 입증하고 지역 배치·키 편중·합의 장애를 실제 부하와 장애 훈련으로 검증해야 함
