## 미리 알고가기

- NewSQL은 관계형 SQL과 강한 정합성을 유지하면서 분산 확장을 노리는 DB 계열임
- 분산 합의는 여러 노드가 같은 순서와 같은 상태를 공유하게 만드는 핵심 기법임
- Spanner와 CockroachDB는 대표적인 분산 SQL 계열로 자주 비교됨

## Ⅰ. 개요

- **정의/개념**: NewSQL은 SQL과 트랜잭션 같은 관계형 DB의 강점을 유지하면서도 분산 환경에서 수평 확장과 고가용성을 확보하도록 설계된 분산 관계형 데이터베이스 계열임
- **배경/필요성**: 글로벌 서비스는 NoSQL 수준의 확장성이 필요하지만 핵심 업무는 여전히 강한 정합성과 SQL 생태계를 요구하므로 둘을 함께 만족시키는 구조가 필요해짐

## Ⅱ. 특징

- SQL과 ACID 트랜잭션을 유지하면서 분산 확장을 시도함
- 분산 계층이 key range를 shard에 배치하고 복제본 합의와 leader 장애 조치를 수행함
- SQL·transaction 인터페이스를 유지하지만 shard key·교차 지역 transaction 특성은 응용 설계에 반영해야 함
- 분산 합의와 교차 노드 조정 비용 때문에 지연 시간이 단일 DB보다 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 관계형 DB | NoSQL | NewSQL |
|:---|:---|:---|:---|
| 정합성 | 강함 | 완화되는 경우가 많음 | 강함 |
| 확장성 | 수직 확장 중심 | 수평 확장에 강함 | 수평 확장을 지향함 |
| 개발 생태계 | SQL 중심 | 모델별 전용 접근 | SQL 중심 |
| 주의점 | 글로벌 확장 부담이 큼 | 조인과 트랜잭션 제약이 있음 | 분산 합의 비용이 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SQL Layer | 표준 SQL과 트랜잭션 인터페이스를 제공함 |
| Distribution Layer | 데이터를 자동 분할하고 적절한 노드로 라우팅함 |
| Consensus / Replication | 복제본 순서와 정합성을 유지함 |
| Transaction Manager | 분산 트랜잭션과 충돌 처리를 담당함 |
| Storage Engine | 실제 데이터를 노드별로 저장하고 복구함 |

```text
애플리케이션 -> SQL 계층 -> 분산 라우팅 -> 복제 노드
                          \-> 트랜잭션/합의 계층
```

## Ⅴ. 원리 및 절차 흐름도

```text
SQL 요청 -> 키 범위 결정 -> 리더 노드 선택 -> 합의/복제 -> 결과 응답
```

1. **SQL 요청 수신**: 애플리케이션이 SQL을 보냄
2. **범위와 노드 결정**: 어떤 키 범위와 노드가 대상인지 찾음
3. **리더와 합의 처리**: 리더가 변경 순서를 정하고 복제본 합의를 거침
4. **트랜잭션 반영**: 커밋 결과를 여러 노드에 반영함
5. **응답 반환**: 성공 여부와 결과를 애플리케이션에 돌려줌

## Ⅵ. 실무 적용 및 유의점

1. 글로벌 금융과 주문 처리처럼 강한 정합성과 분산 확장이 모두 필요한 업무는 NewSQL이 적합하지만 교차 지역 트랜잭션이 많아지면 지연이 커지므로 지역별 트랜잭션 비율과 합의 지연시간과 상위 99% 응답 시간으로 확인함
2. 기존 관계형 시스템을 바로 전면 전환하기보다 병목 테이블과 장애 복원 요구가 큰 영역부터 옮기고 분산 노드 추가 후 성능 개선 폭과 운영 복잡도 증가 수준으로 확인함

## Ⅶ. 결론

- NewSQL은 관계형 정합성과 분산 확장을 함께 노리는 구조이므로 합의 비용을 감당할 업무인지 먼저 판단해야 함
