## Ⅰ. 개요
- 정의: 소프트웨어 개발 및 유지보수 사업에 소요되는 비용을 산정하는 기준임
- 배경: 사업 범위와 기능 규모를 기준으로 발주자와 수행자가 대가 산정 근거를 공유할 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 기능점수(FP) | 간이법, 상세법 | 매우높음 |
| 대가 체계 | 직접비, 제경비, 기술료 | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ SW 대가 ] = [ 직접인건비 ] + [ 제경비 ] + [ 기술료 ] + [ 직접경비 ]
       ^              |            |            |
    FP 기반         실비         인건비의%     연구개발비

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 기능점수(FP) | 사용자 요구 기능의 양을 수치화한 단위 | 건물의 연면적 |
| 직접인건비 | 실제 투입되는 인력의 등급별 노임 단가 | 목수의 일당 |
| 기술료 | 기업이 보유한 노하우와 기술 사용 대가 | 설계 권리금 |

> 요약: 기능 점수를 중심으로 인건비와 부대 비용을 합산하여 산정함

## Ⅲ. 절차
- ASCII 흐름도
  [규모산정] -> [보정계수 적용] -> [단가 곱셈] -> [총원가 산출]
    (FP)         (복잡도 등)       (단가/점)      (부가세 별도)

- 4단계 설명
1. 규모산정: 데이터 기능과 트랜잭션 기능을 식별하여 FP 산출함
2. 보정계수: 규모, 복잡도, 언어, 신뢰도 등 보정계수를 곱하여 보정함
3. 단가적용: 당해 연도 고시된 소프트웨어 기능점수 단가를 적용함
4. 최종합계: 이윤 및 직접경비를 포함하여 사업 대가를 최종 확정함

> 요약: 사용자 기능을 FP로 산정하고 보정계수·단가·직접경비를 적용하여 사업 대가를 계산함

## Ⅳ. 문제점
- 요구사항 불명확으로 인한 초기 산정과 실제 투입 비용 간 괴리 발생함
- 신기술(AI, 클라우드) 도입 시 기존 FP 방식의 적용 한계 및 모호성 존재함

## Ⅴ. 개선방안
- (단기) 제안요청서(RFP) 상세화를 통해 요구사항 분석 정확도 제고함
- (중기) 투입 공수(Man-Month) 방식 지양 및 FP 방식 정착 유도함
- (장기) 가치 기반(Value-based) 및 구독형 모델 대가 산정 체계 마련함

## Ⅵ. 전망
- SaaS 전환 가속화에 따라 사용량 기반(Pay-as-you-go) 대가 체계 비중 확대됨
- 생성형 AI 개발 대가 등 지능형 SW 특성을 반영한 새로운 산정 기준 정립 예상됨
