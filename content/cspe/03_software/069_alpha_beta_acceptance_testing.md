## 미리 알고가기

- 알파 테스트는 개발 조직 통제 환경에서 수행하는 사전 검증임
- 베타 테스트는 실제 사용자 환경에 가까운 조건에서 수행하는 외부 검증임
- 인수 테스트는 계약이나 운영 수용 기준 충족 여부를 판정함

## Ⅰ. 개요

- **정의/개념**: 알파 테스트는 개발사 통제 환경에서 수행하는 사전 사용자 검증이고, 베타 테스트는 실제 사용자가 운영에 가까운 환경에서 수행하는 현장 검증이며, 인수 테스트는 발주자나 운영 주체가 요구 수용 여부를 공식 판단하는 최종 검증 단계임
- **배경/필요성**: 내부 품질 검증만으로는 실제 사용성 문제나 현장 환경 변수를 모두 파악하기 어려우므로, 릴리스 전후에 다른 수준의 사용자 검증 단계를 운영해야 함

## Ⅱ. 특징

- 알파 테스트는 결함 수정 회전이 빠르고 통제가 쉽다
- 베타 테스트는 현실 사용 패턴과 환경 문제를 잘 드러냄
- 인수 테스트는 계약 기준과 운영 수용 여부 판단에 초점이 있다
- 세 단계 목적을 혼동하면 책임과 종료 기준이 흐려질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 알파 테스트 | 베타 테스트 | 인수 테스트 |
|:---|:---|:---|:---|
| 수행 주체 | 개발 조직 내부 | 제한된 실제 사용자 | 고객/운영 주체 |
| 환경 | 통제된 시험 환경 | 실제와 유사한 현장 환경 | 계약/운영 기준 환경 |
| 목적 | 내부 완성도 확인 | 사용자 반응과 현장성 검증 | 수용 여부 판정 |
| 종료 기준 | 주요 결함 정리 | 피드백과 안정성 확인 | 요구 기준 충족 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Test Audience | 누가 검증하는지에 따라 발견되는 결함 유형과 피드백 성격이 달라짐 |
| Environment Fidelity | 실제 운영과 얼마나 유사한지가 발견 품질을 좌우함 |
| Acceptance Criteria | 어떤 조건이면 출시 또는 인수가 가능한지 명확한 기준이 필요함 |
| Feedback Handling | 수집된 피드백을 결함과 개선 의견으로 분류해 후속 조치로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 내부 검증 준비  | --> | 알파/베타 수행 | --> | 인수 기준 판정 | --> | 수정/출시 결정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **내부 검증 준비**: 시나리오와 환경과 종료 기준을 정의함
2. **알파와 베타 수행**: 단계별로 사용자 피드백과 결함을 수집함
3. **인수 기준 판정**: 계약과 운영 수용 조건 충족 여부를 확인함
4. **수정 및 출시 결정**: 결과에 따라 수정하거나 출시함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 알파와 베타를 구분하지 않으면 실제 사용자 피드백과 내부 결함 수정 책임이 섞여 일정 관리가 어려워질 수 있음
   - 해결방안: 단계별 목적과 종료 기준을 분리하고 feedback classification accuracy와 phase exit adherence로 검증함
2. 문제: 베타 환경이 실제 운영과 다르면 현장 결함이 충분히 드러나지 않을 수 있음
   - 해결방안: 환경 유사성을 높이고 beta environment fidelity와 field defect discovery rate로 검증함
3. 문제: 인수 테스트 기준이 모호하면 수용 여부가 감정적 논쟁으로 변할 수 있음
   - 해결방안: 계약형 acceptance criteria를 구체화하고 acceptance dispute count와 sign-off lead time으로 검증함

## Ⅶ. 적용 사례

- 기업용 패키지 제품에서는 알파 테스트를 먼저 수행하고, phase exit adherence와 defect closure rate로 결과를 확인함
- 일반 사용자 대상 앱에서는 베타 프로그램을 운영하고, beta environment fidelity와 field defect discovery rate로 결과를 확인함
- 공공 SI 사업에서는 인수 테스트를 계약 기준으로 수행하고, acceptance dispute count와 sign-off lead time로 결과를 확인함

## Ⅷ. 결론

알파·베타·인수 테스트는 이름만 다른 테스트가 아니라 검증 주체와 환경과 의사결정 목적이 서로 다른 단계임을 명확히 구분해야 함.
