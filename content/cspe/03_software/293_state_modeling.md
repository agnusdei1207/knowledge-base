## Ⅰ. 개요
- 정의: 객체가 가질 수 있는 모든 가능한 상태와 이벤트에 따른 상태 전이를 기술함
- 배경: 임베디드, 실시간 시스템 등 상태 의존적 로직의 복잡성 관리 필요성 증대
- 출제 의도: 객체 생명주기 제어 및 이벤트 처리 메커니즘 설계 역량 평가

## Ⅱ. 구성요소
- ASCII 구조도
  (*) --> [State A] -- Event1 / Action --> [State B]
            |                                 |
            +<---------- Event2 --------------+
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 상태(State) | 객체의 생명주기 동안 유지되는 조건/상황 | 신호등 색깔 |
| 전이(Transition) | 특정 이벤트에 의해 다른 상태로 변하는 통로 | 색깔 변화 |
| 이벤트(Event) | 전이를 유발하는 외부 또는 내부의 자극 | 버튼 누름 |
> 요약: 객체의 유효한 상태 집합과 자극에 의한 동적 변화 규칙을 정의함

## Ⅲ. 절차
- ASCII 흐름도
  Obj Select -> State ID -> Transition ID -> Action Define
- 4단계 설명
1. Obj Select: 생명주기가 복잡하거나 상태 제어가 중요한 객체 선정함
2. State ID: 객체가 존재할 수 있는 고유한 상태들을 식별함
3. Transition ID: 상태를 변화시키는 트리거(이벤트)와 조건을 설정함
4. Action Define: 상태 진입(Entry), 유지(Do), 탈출(Exit) 시 동작 기술함
> 요약: 대상 객체의 상태를 정의하고 이벤트에 따른 전이 경로와 부가 액션을 설정함

## Ⅳ. 문제점
- 독립 상태 변수와 예외 전이가 늘어나면 가능한 상태 조합과 검증 경로가 급격히 증가함

## Ⅴ. 개선방안
- 공통 전이를 상위 상태로 묶는 계층적 상태 머신(HSM)과 합성 상태를 적용함

## Ⅵ. 전망
- 정형 기법(Formal Methods)과 연계한 모델 체킹 및 자동 테스트 케이스 생성 활성화
- CSF: 모든 가능한 상태 조합(Matrix)에 대한 예외 처리 설계가 결함 방지의 핵심임
