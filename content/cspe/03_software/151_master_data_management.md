## Ⅰ. 개요
- **정의**: 기업 핵심 마스터 데이터를 단일 기준으로 통합·관리하는 체계
- **배경/필요성**: 시스템별 고객·제품 데이터가 분산되면 불일치로 의사결정 오류가 발생하므로 단일 원천 확보가 필요함
- **비유**: 회사 전체가 참조하는 공식 전화번호부와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 거버넌스 이해도 | 골든 레코드, 단일 원천 개념 | 단순 DB 통합과 MDM 차이 구분 |

> 요약: 마스터 데이터의 정합성을 보장하는 전사적 데이터 관리 체계임

## Ⅱ. 구성요소
```text
[소스 시스템] ---> [매칭/병합 엔진] ---> [골든 레코드 저장소]
                        |                        |
                   [품질 검증]             [배포/동기화]
                        |                        |
                   [데이터 스튜어드]        [구독 시스템]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 골든 레코드 | 중복 제거 후 생성된 단일 정제 레코드 | 공인 인증 원본 |
| 매칭/병합 엔진 | 유사 레코드를 식별·통합하는 처리기 | 동명이인 판별기 |
| 데이터 스튜어드 | 마스터 데이터의 품질을 관리하는 담당자 | 도서관 사서 |
| 배포/동기화 | 골든 레코드를 하위 시스템에 전파하는 기능 | 공지사항 게시 |

> 요약: 매칭·병합을 통해 골든 레코드를 생성하고 전사에 배포하는 구조임

## Ⅲ. 절차
```text
수집 --> 프로파일링 --> 매칭/병합 --> 배포
```
- 1단계: 수집 — 각 소스 시스템에서 마스터 항목을 추출함
- 2단계: 프로파일링 — 데이터 패턴·품질을 분석하여 이상치를 식별함
- 3단계: 매칭/병합 — 동일 엔티티를 식별하고 골든 레코드로 통합함
- 4단계: 배포 — 정제된 마스터 데이터를 구독 시스템에 동기화함

> 요약: 수집-프로파일링-병합-배포의 4단계로 단일 원천을 확보함

## Ⅳ. 문제점
- 데이터 불일치: 시스템 간 코드 체계 상이 — 병합 시 오매칭 발생
- 거버넌스 부재: 데이터 소유권 미정의 — 변경 시 책임 소재 불명확
- 실시간 동기화 지연: 배치 기반 배포 — 시스템 간 일시적 불일치 발생

> 요약: 코드 불일치, 거버넌스 부재, 동기화 지연이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 전사 코드 표준화 및 매칭 규칙 정교화
2. 중기: 데이터 스튜어드 제도 도입 및 소유권 정책 수립
3. 장기: CDC 기반 실시간 동기화 아키텍처 전환 (156 참조)

> 요약: 표준화, 거버넌스 제도화, 실시간 동기화로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: AI 기반 자동 매칭·병합으로 골든 레코드 생성 정확도 향상
- 기술사적 판단: 데이터 메시 환경에서 도메인별 분산 MDM 패턴 확산 예상
- 기술사 제언: 데이터 거버넌스와 MDM을 통합 설계하여 전사 데이터 신뢰도를 확보할 필요
