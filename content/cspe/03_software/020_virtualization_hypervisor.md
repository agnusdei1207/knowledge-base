## 미리 알고가기

- 가상화는 물리 자원을 논리 인스턴스로 분할해 제공하는 기술임
- Type 1 하이퍼바이저는 하드웨어 위에서 직접 동작함
- Type 2 하이퍼바이저는 호스트 OS 위에서 동작함

## 작성 근거(검토용)

- 가상화는 물리 자원 분할·VM 격리·관리 자동화 관계로 설명함
- Type 1과 Type 2는 실행 위치·자원 경로·장애 범위·운영 기능·적용 환경으로 비교함
- 일반 VM 생명주기 절차는 삭제하고 데이터센터·개발 환경의 선택 조건으로 회수함

## Ⅰ. 개요

- **정의/개념**: 가상화는 물리 서버 자원을 가상머신 단위로 분리해 여러 OS와 애플리케이션이 독립 시스템처럼 실행되게 하는 기술이며, 하이퍼바이저는 Type 1과 Type 2로 나뉨
- **배경/필요성**: 서버 통합·자원 분할·실행 환경 배포를 위해 하나의 물리 장비에서 여러 가상머신을 격리할 구조가 필요함

## Ⅱ. 특징

- 가상머신마다 독립 OS와 자원 격리를 제공함
- 관리면 API로 스냅샷·마이그레이션·이미지 배포 절차를 자동화함
- Type 1은 운영 서버에, Type 2는 호스트 OS가 필요한 개발·시험 환경에 배치함
- 하이퍼바이저 위치와 하드웨어 가상화 지원 수준이 VM exit·I/O 경로·격리 경계를 결정함

## Ⅲ. 종류 및 비교

| 판단 기준 | Type 1 | Type 2 |
|:---|:---|:---|
| 위치 | 하드웨어 위 직접 실행 | 호스트 OS 위 실행 |
| 실행·격리 경로 | 하이퍼바이저가 하드웨어 자원을 직접 중재 | 호스트 OS와 하이퍼바이저 계층을 함께 경유 |
| 운영 목적 | 데이터센터, 클라우드 | 개발, 실습, 개인 환경 |
| 장애 영향 | 하이퍼바이저 중심 | 호스트 OS 장애 전파 가능 |
| 관리 기능 | 중앙 관리·마이그레이션·클러스터 | 호스트별 설치·스냅샷 |

> 요약: Type 1은 하드웨어 자원을 직접 중재하고, Type 2는 호스트 OS의 장치·자원 경로를 함께 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 하이퍼바이저 | vCPU·메모리·I/O를 가상화하고 VM별 자원 접근을 중재함 |
| 가상머신 | 게스트 OS와 애플리케이션을 포함하는 격리·배포 단위임 |
| 가상 자원 모델 | 가상 디스크·vNIC·vSwitch를 물리 자원에 매핑함 |
| 관리면 | 템플릿·스냅샷·마이그레이션·자원 정책을 관리함 |

> 요약: 하이퍼바이저가 가상 자원을 물리 자원에 매핑하고 관리면이 VM의 배포·이동·복구를 제어함.

## Ⅵ. 실무 사례

1. 데이터센터는 Type 1의 CPU·메모리 상한을 설정하고 CPU 준비 대기시간과 메모리 과할당률을 확인함
2. 개발 환경은 Type 2 표준 이미지를 배포하고 VM 생성시간과 호스트 자원 사용률을 확인함

## Ⅶ. 결론

- Type 1·Type 2는 격리 수준과 호스트 OS 의존성·관리 기능 요구에 따라 선택함
