## 미리 알고가기

- 가상화는 물리 자원을 논리 인스턴스로 분할해 제공하는 기술임
- Type 1 하이퍼바이저는 하드웨어 위에서 직접 동작함
- Type 2 하이퍼바이저는 호스트 OS 위에서 동작함

## Ⅰ. 개요

- **정의/개념**: 가상화는 물리 서버 자원을 가상머신 단위로 분리해 여러 OS와 애플리케이션이 독립 시스템처럼 실행되게 하는 기술이며, 구현 핵심인 하이퍼바이저는 Type 1과 Type 2로 나뉨
- **배경/필요성**: 서버 통합과 자원 효율화와 빠른 배포를 위해 하나의 물리 장비에서 여러 실행 환경을 안전하게 운용해야 하므로, 격리와 관리 자동화를 제공하는 가상화 계층이 필요함

## Ⅱ. 특징

- 가상머신마다 독립 OS와 자원 격리를 제공함
- 스냅샷과 마이그레이션과 이미지 배포 같은 운영 자동화가 쉬움
- Type 1은 운영 서버에, Type 2는 개발과 테스트 환경에 적합함
- 성능과 보안은 하이퍼바이저 위치와 하드웨어 가상화 지원 수준에 크게 좌우됨

## Ⅲ. 종류 및 비교

| 판단 기준 | Type 1 | Type 2 |
|:---|:---|:---|
| 위치 | 하드웨어 위 직접 실행 | 호스트 OS 위 실행 |
| 성능과 격리 | 오버헤드가 낮고 강한 격리 | 호스트 영향으로 오버헤드 증가 |
| 운영 목적 | 데이터센터, 클라우드 | 개발, 실습, 개인 환경 |
| 장애 영향 | 하이퍼바이저 중심 | 호스트 OS 장애 전파 가능 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Hypervisor | vCPU와 메모리와 I/O를 가상화해 VM 실행과 자원 격리를 담당함 |
| Virtual Machine | 게스트 OS와 애플리케이션을 담는 논리 실행 단위로 배포와 복구 대상이 됨 |
| Virtual Resource Model | 가상 디스크와 vNIC와 vSwitch가 물리 자원을 논리 자원으로 재구성함 |
| Management Plane | 템플릿과 스냅샷과 마이그레이션과 정책 자동화를 제공해 운영 효율을 높임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 자원 추상화    | --> | VM 생성        | --> | 실행 및 격리   | --> | 운영 자동화    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **자원 추상화**: CPU와 메모리와 스토리지와 네트워크를 논리 자원으로 나눔
2. **VM 생성**: 이미지와 vCPU와 vRAM과 가상 장치를 구성함
3. **실행 및 격리**: 하이퍼바이저가 VM별 자원 접근을 통제하며 실행함
4. **운영 자동화**: snapshot과 migration과 모니터링과 복구를 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 과도한 자원 overcommit과 I/O 에뮬레이션은 가상머신 응답성을 크게 떨어뜨릴 수 있음
   - 해결방안: workload 기반 자원 한도를 설정하고 CPU ready time과 p99 latency로 검증함
2. 문제: 하이퍼바이저와 관리 콘솔 보안이 약하면 전체 가상화 환경이 동시에 노출될 수 있음
   - 해결방안: 관리망 분리와 RBAC를 적용하고 hardening compliance와 audit finding count로 검증함
3. 문제: VM 수가 무분별하게 늘어나면 운영 복잡도와 라이선스 비용이 급증할 수 있음
   - 해결방안: lifecycle policy와 표준 템플릿을 운영하고 orphan VM count와 provision time으로 검증함

## Ⅶ. 적용 사례

- 데이터센터 서버 통합에서는 Type 1 기반 가상화를 사용하고, CPU ready time과 consolidation ratio로 결과를 확인함
- 개발 환경에서는 Type 2 하이퍼바이저를 제한적으로 사용하고, provision time과 host impact rate로 결과를 확인함
- 클라우드 운영에서는 스냅샷과 마이그레이션을 자동화하고, migration success rate와 hardening compliance로 결과를 확인함

## Ⅷ. 결론

가상화의 핵심 가치는 물리 서버를 더 많이 쓰는 것이 아니라 격리와 자동화를 유지하며 자원을 논리 서비스 단위로 재구성하는 데 있음.
