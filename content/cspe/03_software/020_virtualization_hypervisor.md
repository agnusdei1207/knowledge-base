## Ⅰ. 개요
- **정의**: 하나의 물리 자원을 논리적으로 분할하여 독립된 다수의 실행 환경을 제공하는 기술
- **배경/필요성**: 서버당 평균 자원 이용률이 낮아 물리 자원을 효율 공유할 필요가 있음
- **비유**: 하나의 건물(물리 서버)을 벽으로 나누어 여러 세입자(VM)에게 독립 공간을 제공하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 기반 기술 이해 | Type-1/Type-2 하이퍼바이저 구분 | 전가상화 vs 반가상화 차이 및 HW 지원(VT-x) 역할 명시 |

> 요약: 하이퍼바이저를 통해 물리 자원을 다중 논리 환경으로 분할·격리하는 기술임

## Ⅱ. 구성요소
```text
+-----+  +-----+  +-----+
| VM1 |  | VM2 |  | VM3 |    <-- Guest OS + App
+-----+  +-----+  +-----+
---------Hypervisor----------    <-- VMM
------Physical Hardware------    <-- CPU, Memory, I/O
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 하이퍼바이저(VMM) | 물리 자원을 VM에 분배·격리하는 제어 계층 | 건물 관리인 |
| 가상 머신(VM) | Guest OS가 실행되는 독립 논리 환경 | 독립 사무실 |
| vCPU/vMemory | 물리 CPU·메모리를 논리 분할한 가상 자원 | 사무실별 할당 전력·면적 |
| 가상 I/O | 물리 NIC·디스크를 에뮬레이션 또는 패스스루 제공 | 공용 우편함 vs 전용 우편함 |

> 요약: 하이퍼바이저가 CPU·메모리·I/O를 가상화하여 VM별 격리 환경을 제공함

## Ⅲ. 절차
```text
자원 분할 --> VM 생성 --> 명령 트랩 --> 자원 중재
```
- 1단계: 하이퍼바이저가 물리 CPU·메모리·I/O를 논리 파티션으로 분할
- 2단계: 가상 머신 정의(vCPU 수, vMemory 크기, 디스크 이미지)에 따라 VM 인스턴스 생성
- 3단계: Guest OS의 특권 명령이 VMExit 트랩으로 하이퍼바이저에 전달됨
- 4단계: 하이퍼바이저가 트랩된 명령을 에뮬레이션하고 자원 경합을 중재

> 요약: 자원 분할-VM 생성-트랩-중재 흐름으로 다중 OS를 동시 실행함

## Ⅳ. 문제점
- 가상화 오버헤드: VMExit/VMEntry 전환 비용 — 트랩 빈도가 높으면 성능 저하 발생
- 자원 과할당: 물리 자원 초과 할당 — VM 간 자원 경합으로 QoS 편차 발생
- 보안 경계 침투: 하이퍼바이저 취약점 — VM Escape 시 호스트 전체가 노출됨

> 요약: 트랩 오버헤드·자원 과할당·VM Escape가 가상화의 3대 과제임

## Ⅴ. 개선방안
1. 단기: HW 가상화 확장(VT-x, EPT)으로 트랩 빈도 감소 및 주소 변환 가속
2. 중기: 자원 예약(Reservation) + 상한(Limit) 정책으로 과할당 시 QoS 하한 보장
3. 장기: 마이크로 VMM 아키텍처 및 형식 검증(Formal Verification)으로 공격 표면 최소화

> 요약: HW 지원, 자원 정책, 마이크로 VMM으로 가상화 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 컨테이너(경량 가상화)와 기밀 컴퓨팅(TEE) 결합으로 격리 수준 세분화
- 기술사적 판단: VM 기반 IaaS에서 컨테이너·서버리스로 추상화 계층이 상향 이동 중임
- 기술사 제언: 워크로드 특성에 따라 VM·컨테이너·유니커널을 적합하게 선택 필요
