# 📖 【암기용】 개념 완전 이해

## 한눈에
- **가상화 (Virtualization)**: 하나의 물리적 서버를 여러 개의 논리적 서버(VM)로 나누어 쓰는 기술. **'추상화'**를 통해 자원 효율을 극대화함.
- **하이퍼바이저 (Hypervisor)**: 물리 자원과 가상 자원 사이를 중재하며 여러 운영체제(Guest OS)를 동시에 실행시키는 **가상화 관리 소프트웨어**.
- **분류**:
    - **Type 1 (Native/Bare-metal)**: 하드웨어 위에 바로 하이퍼바이저가 올라감. (성능 좋음, 서버용 - Xen, KVM, ESXi)
    - **Type 2 (Hosted)**: 일반 OS 위에서 애플리케이션처럼 실행됨. (구현 쉬움, 개인용 - VirtualBox, VMware Workstation)

## 깊이 이해
- **가상화의 핵심: Trap-and-Emulate**: Guest OS가 특권 명령(자원 직접 제어 등)을 내리면, 하이퍼바이저가 이를 가로채서(Trap) 가상 자원에 맞게 흉내(Emulate)내어 처리함.
- **CPU의 특권 계층 (Ring)**: 
    - 일반 OS는 Ring 0(최고 권한)을 가짐. 
    - 가상화 환경에서는 하이퍼바이저가 Ring 0을 차지하고, Guest OS는 강제로 Ring 1로 밀려남 (이게 성능 하락의 원인).
- **하드웨어 지원 가상화 (Intel VT-x / AMD-V)**: CPU가 하이퍼바이저를 위한 전용 모드(Root Mode)를 제공하여, Trap-and-Emulate 오버헤드를 획기적으로 줄여줌.
- **가상화의 가치**: 서버 통합(Server Consolidation), 격리(Isolation)를 통한 보안 강화, 유연한 자원 배분.

## 연결 개념
- **Full vs Para Virtualization (021)**: 하이퍼바이저와 대화하는 방식의 차이.
- **Container (170)**: 하이퍼바이저 없이 OS 커널을 공유하는 더 가벼운 가상화.
- **Cloud Computing (161)**: 하이퍼바이저 기술 위에서 탄생한 서비스 모델.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 하드웨어 자원을 논리적 계층으로 **추상화(Abstraction)**하여, 단일 물리 노드에서 다수의 독립적인 실행 환경을 구동하는 기술임.
> 2. **기술적 핵심**: Guest OS의 특권 명령을 가로채는 **Trap-and-Emulate**와 주소 변환을 위한 **이중 페이징(Shadow Page Table/EPT)** 기술이 핵심임.
> 3. **판단**: 고성능 엔터프라이즈 환경은 **Type 1**을, 개발 및 테스트의 편의성이 중요하면 **Type 2** 하이퍼바이저를 채택함.

## Ⅰ. 자원 효율화의 혁명, 가상화와 하이퍼바이저 개요
- **가상화**: 물리 자원을 논리적 단위로 분리/통합하여 자원 활용의 유연성을 극대화하는 기술.
- **하이퍼바이저 (VMM)**: 호스트 컴퓨터 하나에서 다수의 OS를 동시에 실행하기 위한 가상화 엔진.

## Ⅱ. 하이퍼바이저의 두 가지 유형 비교

### 1. 유형별 아키텍처 (ASCII Diagram)
```text
      [Type 1: Bare-metal]             [Type 2: Hosted]
    ┌───────────────────────┐        ┌───────────────────────┐
    │   Guest OS | Guest OS │        │   Guest OS | Guest OS │
    ├───────────────────────┤        ├───────────────────────┤
    │      Hypervisor       │        │      Hypervisor       │
    ├───────────────────────┤        ├───────────────────────┤
    │       Hardware        │        │        Host OS        │
    └───────────────────────┘        ├───────────────────────┤
                                     │       Hardware        │
                                     └───────────────────────┘
```

### 2. 유형별 상세 비교표
| 구분 | Type 1 (Bare-metal) | Type 2 (Hosted) |
|:---:|:---|:---|
| **위치** | 하드웨어 바로 위 (OS 미필요) | 기존 Host OS 위 (애플리케이션 형태) |
| **성능** | 높음 (오버헤드 적음) | 상대적으로 낮음 (Host OS 간섭) |
| **안정성** | 높음 (Host OS 장애 전파 없음) | Host OS 상태에 의존 |
| **사용 사례** | 엔터프라이즈 서버, 클라우드(AWS, Azure) | 개인 PC, 소프트웨어 개발/테스트 |
| **대표 솔루션** | Xen, KVM, VMWare ESXi, Hyper-V | VMWare Workstation, VirtualBox |

## Ⅲ. 하이퍼바이저의 핵심 동작 원리

1. **특권 명령 제어**: Guest OS가 I/O나 메모리 할당 등 특권 명령을 실행하면 CPU 트랩 발생 -> 하이퍼바이저가 제어권을 얻어 안전하게 처리.
2. **CPU 가상화**: 여러 VM이 CPU 타임 슬라이스를 공평하게 나누어 쓰도록 스케줄링.
3. **메모리 가상화**: 
    - **Shadow Page Table**: 하이퍼바이저가 Guest와 물리 주소 사이의 지도를 직접 관리.
    - **EPT (Extended Page Table)**: 하드웨어(CPU)가 주소 변환을 2단계로 직접 수행 (성능 우수).

## Ⅳ. 가상화의 3대 핵심 속성 (Popek & Goldberg)
1. **효율성 (Efficiency)**: 대부분의 명령어가 인터프리팅 없이 하드웨어에서 직접 실행되어야 함.
2. **자원 제어 (Resource Control)**: 하이퍼바이저가 하드웨어 자원을 완전히 장악해야 함.
3. **동등성 (Equivalence)**: 가상 환경에서 실행되는 소프트웨어는 물리 환경과 동일하게 동작해야 함.

## Ⅴ. 하이퍼바이저 vs 컨테이너 (비교 심화)

| 비교 항목 | 하이퍼바이저 (VM) | 컨테이너 (Docker 등) |
|:---:|:---|:---|
| **격리 수준** | **HW 레벨 (강력함)** | OS 레벨 (프로세스 격리) |
| **커널 공유** | 개별 Guest OS 커널 사용 | **Host OS 커널 공유** |
| **부팅 속도** | 분 단위 (OS 기동 필요) | 초 단위 (프로세스 실행) |
| **자원 사용** | 무거움 (메모리 중복 점유) | 매우 가벼움 |

## Ⅵ. 기술사 관점의 결론 및 제언
- 하이퍼바이저 가상화는 **'완벽한 격리'**를 제공하여 클라우드 보안의 초석이 됨.
- **실무 제언**: 최근에는 하이퍼바이저의 격리성과 컨테이너의 가벼움을 결합한 **Kata Containers**나, 아주 작은 기능만 남긴 **MicroVM (Firecracker)** 기술이 서버리스(Serverless) 컴퓨팅의 핵심으로 떠오르고 있음. 시스템 요구사항에 따라 격리 강도와 오버헤드 사이의 적절한 기술 스택을 선정해야 함.
