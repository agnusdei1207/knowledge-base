## 미리 알고가기

- 가상화는 물리 자원을 논리 인스턴스로 분할해 제공하는 기술임
- Type 1 하이퍼바이저는 하드웨어 위에서 직접 동작함
- Type 2 하이퍼바이저는 호스트 OS 위에서 동작함

## Ⅰ. 개요

- **정의/개념**: 가상화는 물리 서버 자원을 가상머신 단위로 분리해 여러 OS와 애플리케이션이 독립 시스템처럼 실행되게 하는 기술이며, 하이퍼바이저는 Type 1과 Type 2로 나뉨
- **배경/필요성**: 서버 통합, 자원 분할, 빠른 배포를 위해 하나의 물리 장비에서 여러 실행 환경을 격리해 운용해야 함

## Ⅱ. 특징

- 가상머신마다 독립 OS와 자원 격리를 제공함
- 관리면 API로 스냅샷·마이그레이션·이미지 배포 절차를 자동화함
- Type 1은 운영 서버에, Type 2는 호스트 OS가 필요한 개발·시험 환경에 배치함
- 하이퍼바이저 위치와 하드웨어 가상화 지원 수준이 VM exit·I/O 경로·격리 경계를 결정함

## Ⅲ. 종류 및 비교

| 판단 기준 | Type 1 | Type 2 |
|:---|:---|:---|
| 위치 | 하드웨어 위 직접 실행 | 호스트 OS 위 실행 |
| 실행·격리 경로 | 하이퍼바이저가 하드웨어 자원을 직접 중재 | 호스트 OS와 하이퍼바이저 계층을 함께 경유 |
| 운영 목적 | 데이터센터, 클라우드 | 개발, 실습, 개인 환경 |
| 장애 영향 | 하이퍼바이저 중심 | 호스트 OS 장애 전파 가능 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Hypervisor | vCPU와 메모리와 I/O를 가상화해 VM 실행과 자원 격리를 담당함 |
| Virtual Machine | 게스트 OS와 애플리케이션을 담는 논리 실행 단위로 배포와 복구 대상이 됨 |
| Virtual Resource Model | 가상 디스크와 vNIC와 vSwitch가 물리 자원을 논리 자원으로 재구성함 |
| Management Plane | 템플릿, 스냅샷, 마이그레이션, 정책 자동화를 제공해 운영 작업을 표준화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 자원 추상화    | --> | VM 생성        | --> | 실행 및 격리   | --> | 운영 자동화    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **자원 추상화**: CPU와 메모리와 스토리지와 네트워크를 논리 자원으로 나눔
2. **VM 생성**: 이미지와 vCPU와 vRAM과 가상 장치를 구성함
3. **실행 및 격리**: 하이퍼바이저가 VM별 자원 접근을 통제하며 실행함
4. **운영 자동화**: snapshot과 migration과 모니터링과 복구를 수행함

## Ⅵ. 실무 적용 및 유의점

1. 데이터센터와 클라우드에서는 Type 1 하이퍼바이저를 쓰되 자원 overcommit과 관리면 보안이 동시에 흔들리지 않도록 CPU와 메모리 한도와 관리망 분리를 적용하고 CPU ready time과 p99 latency와 hardening compliance로 확인함
2. 개발과 테스트 환경에서는 Type 2 하이퍼바이저를 제한적으로 쓰되 호스트 OS 장애와 자원 간섭이 커지지 않도록 표준 이미지와 호스트 영향 기준을 두고 provision time과 host impact rate로 확인함

## Ⅶ. 결론

가상화는 물리 서버 수를 늘리는 기술이 아니라, 격리와 자동화를 유지하며 자원을 논리 서비스 단위로 재구성하는 기술임.

## 작성 근거(검토용)

- 가상화는 평가어보다 물리 자원 분할, 실행 환경 격리, 관리 자동화라는 기능 관계로 설명해야 함
- Type 1과 Type 2 비교는 하이퍼바이저 위치가 성능, 격리, 장애 영향에 어떻게 연결되는지 보이도록 유지함
