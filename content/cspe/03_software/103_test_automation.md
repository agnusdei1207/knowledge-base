- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Code] -> [CI Server] -> [Automation Tool] -> [Reports]
                                 |
                          [Script/Framework]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 프레임워크 | 테스트 스크립트 작성 및 실행 구조 | 공장 라인 |
| 데이터 주도 | 데이터와 스크립트를 분리하여 관리 | 템플릿 |
| 키워드 주도 | 동작 중심의 키워드로 테스트 기술 | 명령어 세트 |

> 요약: 테스트 수행을 자동화하여 효율성과 정확성을 높이는 기술임.

## Ⅲ. 절차
- ASCII 흐름도
  Manual TC -> Scripting -> Exec -> Log -> Analysis

1. 대상 선정: 반복적이고 정형화된 테스트 케이스 선별함.
2. 도구 선정: 웹(Selenium), 모바일(Appium) 등 도구 결정함.
3. 스크립트 개발: 재사용 가능한 모듈형 스크립트 작성함.
4. 실행 및 모니터링: 스케줄링 및 결과 리포팅 자동 수행함.

> 요약: 반복 업무 자동화로 테스터는 고부가가치 분석 업무에 집중함.

## Ⅳ. 문제점
- 초기 구축 비용 및 스크립트 유지보수 부하가 큼.
- UI 변경 시 스크립트 오류 빈발로 안정성 확보 어려움.

## Ⅴ. 개선방안
- Object Repository 활용으로 변경 영향 최소화 및 추상화함.
- 셀프 힐링(Self-healing) 기능 탑재 도구 도입으로 유지보수 자동화함.

## Ⅵ. 전망
- AI/ML 기반 자가 학습 테스트 및 자동 결함 분석 기능 확산됨.
- CSF: 비즈니스 가치 중심의 자동화 범위 설정 및 ROI 분석임.
