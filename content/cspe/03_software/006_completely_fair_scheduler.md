# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 리눅스의 기본 스케줄러로, 고정된 타임 퀀텀 대신 각 프로세스에 할당된 '가상 런타임(vruntime)'을 기준으로 완벽한 공평성을 추구하는 기법
- **왜 필요한가**: MLFQ처럼 복잡한 큐와 퀀텀 파라미터 튜닝 없이도, 이론적으로 모든 프로세스가 CPU를 공평하게 나눠 쓰게 만들기 위함이다.
- **핵심 직관**: 모든 사람에게 똑같은 식사 시간을 주고 타이머를 잰다. 지금까지 가장 적게 먹은 사람(vruntime이 가장 작은 프로세스)에게 다음 숟가락을 우선적으로 준다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| vruntime (가상 런타임) | 프로세스가 지금까지 실행된 누적 시간 | 스톱워로 잰 누적 식사 시간 |
| 타겟 레이턴시 (Target Latency) | 모든 프로세스가 한 번씩 실행되는 데 걸리는 기준 시간 | 모두 한 입씩 먹는 데 걸리는 한 바퀴 시간 |
| 레드-블랙 트리 (Red-Black Tree) | CFS가 프로세스를 정렬해 두는 이진 탐색 트리 | 식사 시간이 적은 사람을 제일 왼쪽에 세우는 줄 |
| 가중치 (Weight) | 프로세스의 우선순위(NICE 값)를 반영하는 비율 | VIP에게 스톱워치가 더 천천히 가게 하는 배율 |

## 깊이 이해
- **배경·문제의식**: O(1) 스케줄러나 MLFQ는 타임 퀀텀을 정적으로 계산하므로 휴리스틱(Heuristics, 튜닝 파라미터)이 많아 유지보수가 어렵다. 리눅스는 "수학적 공평함"을 목표로 휴리스틱을 최소화한 CFS를 2.6.23에 도입했다.
- **작동 원리**: 
  1. 스케줄러는 R-B 트리의 가장 왼쪽(vruntime이 제일 작은) 노드를 선택해 실행한다.
  2. 실행된 만큼 해당 프로세스의 vruntime을 증가시킨 뒤 다시 트리에 넣는다.
  3. I/O 대기(Sleep)로 인해 vruntime이 너무 뒤처진 프로세스가 깨어나면, 현재 트리의 최소값 근처로 vruntime을 보정해준다(독점 방지).
- **구체 예시**: A, B, C 세 프로세스가 있고 타겟 레이턴시가 30ms라면, 각 10ms씩 할당받는다. A가 우선순위(가중치)가 두 배 높다면, A의 스톱워치(vruntime)는 실제 시간보다 절반의 속도로 흐르게 되어 결과적으로 더 자주 CPU를 차지하게 된다.
- **흔한 오해·주의점**: CFS의 시간 복잡도는 트리 삽입/삭제 때문에 O(log N)이다. O(1) 스케줄러보다 이론적으로 느리지만, 캐시 효과와 나노초 단위 정밀 제어 덕분에 실제 체감 성능과 공평성이 훨씬 뛰어나다.

## 연결 개념
- 스케줄링 알고리즘 (004 참조) — 과거 스케줄러들의 한계
- MLFQ (005 참조) — CFS가 대체한 휴리스틱 기반 스케줄러

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CFS는 복잡한 다중 큐나 고정된 타임 퀀텀 없이, 가상 런타임(`vruntime`)을 Red-Black Tree로 관리하여 수학적 공평성을 달성하는 리눅스 표준 스케줄러다.
> 2. **가치**: 프로세스의 I/O 및 CPU 점유 이력에 대한 자의적 휴리스틱(Heuristics)을 제거하고, 나노초(ns) 단위의 정밀한 스케줄링을 구현한다.
> 3. **판단 포인트**: 우선순위(Nice)는 퀀텀 크기가 아니라 `vruntime`의 증가 속도(가중치)로 반영하여, 우선순위 역전과 불공평성을 근본적으로 차단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 리눅스 현대 스케줄링 아키텍처 이해 | vruntime 개념, Red-Black Tree, 타겟 레이턴시 | O(1) 스케줄러의 특징과 혼동 (배열 vs 트리) |
| 우선순위 반영 및 공평성 구현 메커니즘 | Nice 값에 따른 가중치(Weight)와 vruntime 증가율 반비례 | "우선순위가 높으면 큐 최상단 배치" 식 서술 |
| I/O 바운드 프로세스 처리 방안 | 슬립(Sleep) 프로세스 깨어날 때 vruntime 보상(Compensation) | 독점(Starvation) 방어 기법 누락 |

> 요약: CFS는 큐 대신 트리를 사용하고, 휴리스틱 대신 가상 런타임 계산을 통해 완벽한 공평 분배(Completely Fair)를 구현한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 모든 프로세스가 이상적인 멀티태스킹 CPU를 공평하게 공유하는 모델을 소프트웨어적으로 근사한 리눅스 스케줄러
- 배경: 기존 O(1) 스케줄러의 복잡한 휴리스틱(상호작용 판별 로직) 유지보수 한계 및 멀티미디어 환경에서의 응답성 저하
- 필요성: 단순하고 수학적인 스케줄링 모델을 통해, 시스템 부하에 상관없이 일관성 있는 응답성과 정밀도(나노초 단위) 보장 필수

---

## Ⅱ. 구조 및 구성요소

```text
Red-Black Tree (Run Queue 역할)
        [ Root: vruntime=100 ]
         /                  \
[ Left: vruntime=50 ]    [ Right: vruntime=150 ]
 (가장 작은 값: 다음 선택 대상)
```

| 구성요소 | 역할 | 연산 기준 |
|:---|:---|:---|
| 가상 런타임 (vruntime) | 프로세스가 CPU를 점유한 누적 가상 시간 | `실제시간 × (기준 가중치 / 프로세스 가중치)` |
| 가중치 (Weight) | 프로세스의 Nice 값(-20~19)에 따른 할당 배율 | Nice 값이 낮을수록 가중치 증가 |
| Red-Black Tree | 프로세스들을 vruntime 기준으로 정렬 및 보관 | O(log N) 탐색/삽입 시간 복잡도 |
| Target Latency | 모든 프로세스가 한 번씩 실행되는 목표 주기 | 프로세스 수에 비례하여 동적 조정 |

> 요약: 스케줄러는 트리의 가장 왼쪽 노드(최소 vruntime)를 선택하며, 우선순위가 높은 프로세스는 vruntime이 천천히 증가하여 더 자주 선택된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
트리 좌측 최하단 노드(min_vruntime) 선택 -> CPU 할당
  -> 나노초 단위 실제 실행 시간 누적
  -> 가중치 반영하여 vruntime 갱신
  -> 갱신된 vruntime 위치로 트리에 재삽입
```

- 1단계 [선택]: Red-Black Tree에서 가장 왼쪽(Leftmost)에 있는, 즉 vruntime이 가장 작은 프로세스 선택
- 2단계 [실행 및 측정]: 할당된 동적 타임 슬라이스(타겟 레이턴시 / 총 프로세스 수)만큼 CPU 실행 후, 실제 사용 시간을 나노초 단위로 측정
- 3단계 [vruntime 갱신]: 측정된 실제 실행 시간에 프로세스의 가중치 비율을 곱해 vruntime을 증가시킴
- 4단계 [재정렬]: 증가된 vruntime 값을 기준으로 프로세스를 Red-Black Tree의 알맞은 위치에 재삽입

> 요약: 스케줄러는 끊임없이 vruntime이 가장 작은 프로세스에게 CPU를 몰아주어 전체적인 평형(Fairness)을 맞춘다.

---

## Ⅳ. 특징

- 동적 타임 슬라이스: 고정된 타임 퀀텀을 버리고, 실행 중인 프로세스 수와 타겟 레이턴시에 따라 할당 시간을 동적으로 나눔
- 휴리스틱 최소화: "이 프로세스는 I/O 바운드인가?"를 추측하는 로직 없이, 오직 vruntime 단일 지표로 스케줄링 결정
- 최소 할당 시간(min_granularity): 컨텍스트 스위칭 오버헤드를 막기 위해 프로세스당 최소 할당 보장 시간(예: 1ms)을 설정

> 요약: CFS는 복잡도를 낮추면서 정밀도를 높였으나, 구조적 한계로 인해 O(1) 대비 스케줄링 결정 자체의 연산량은 O(log N)으로 늘었다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존 O(1) 스케줄러 | CFS (Completely Fair Scheduler) | 선택 기준 |
|:---|:---|:---|:---|
| 자료구조 | Active/Expired Array (배열) | Red-Black Tree | O(1) vs O(log N) 트레이드오프 |
| 응답성 판별 | 휴리스틱 점수 계산 | vruntime 일원화 | 로직의 복잡성 제거 |
| 타임 퀀텀 | 고정 퀀텀 (Static) | 타겟 레이턴시 기반 동적 할당 | 부하 변동에 대한 적응력 |

> 요약: O(log N)의 페널티에도 불구하고, 트리 캐싱 최적화와 공평성 이점이 더 커 현대 범용 OS의 표준으로 자리 잡았다.

**리스크·대응 (기본은 불릿):**
- I/O 바운드 폭주(Starvation 보상 악용): 오랫동안 대기(Sleep)했던 프로세스가 깨어나면서 vruntime이 지나치게 작아 CPU를 독점할 위험 → 깨어날 때 현재 트리의 `min_vruntime` 값 근처로 보정(Compensation)하여 독점 억제
- 멀티코어 밸런싱 실패: 특정 코어의 트리에만 연산이 몰려 코어 간 불균형 발생 → 주기적 로드 밸런서(Load Balancer)가 트리 간 vruntime 차이를 모니터링하여 프로세스 마이그레이션 (지표: Run Queue 밸런스)

**도입 후 점검 지표 (기본은 불릿):**
- 성능/효율: 스케줄링 지연(Scheduling Latency), 프로세스 마이그레이션 횟수
- 품질/운영: Run Queue 사이즈, `perf sched` 프로파일링 지표

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. cgroups 연계 제어: 컨테이너(Docker/K8s) 환경에서 CFS Bandwidth Control(quota/period)을 적용해 CPU 사용량을 하드 리밋으로 통제
2. 스케줄링 클래스 분리: 완벽한 실시간 보장이 필요한 작업은 CFS를 우회하여 RT 클래스(`SCHED_FIFO`)로 명시적 분리 지정
3. 튜닝 파라미터 적용: `sysctl`을 통해 `sched_latency_ns`와 `sched_min_granularity_ns`를 조정, 웹 서버 등 응답성 중시 환경에 맞춤 최적화

**결론 (2줄):**
- 기술사 판단: CFS는 가상 시간 개념을 실용화하여 스케줄링의 난제(공평성과 성능)를 수려하게 푼 아키텍처이나, 초저지연(Ultra-low latency) 요구에는 여전히 RT 제어가 필요하다.
- 향후 방향: 최근 클라우드 네이티브 환경에서는 BPF 기반으로 커널 수정 없이 동적 스케줄링 정책을 주입하는 eBPF 스케줄러(sched_ext) 연구가 가속화되고 있다.
