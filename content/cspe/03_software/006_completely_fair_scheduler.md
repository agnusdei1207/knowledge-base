# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 완전 공정 스케줄러(CFS)는 리눅스의 기본 스케줄러로, 고정 타임 퀀텀 대신 각 프로세스의 **가상 런타임(vruntime)**을 **레드-블랙 트리**로 관리하며, 지금까지 가장 적게 실행된 프로세스에 CPU를 주어 수학적 공평성을 추구한다.
- **왜 필요한가**: MLFQ·O(1) 스케줄러는 "이 작업이 대화형인가"를 추측하는 휴리스틱과 퀀텀 파라미터가 많아 유지보수가 어렵다. 그런 추측 없이, 오직 '누가 덜 썼나'라는 단일 지표로 공평하게 나누기 위함이다. (선점·문맥 전환·응답 시간 등 일반 배경은 004 참조)
- **핵심 직관**: 모두에게 똑같은 식사 시간을 주고 각자의 누적 식사 시간을 스톱워치로 잰다. 지금까지 **가장 적게 먹은 사람**에게 다음 숟갈을 준다. VIP(높은 우선순위)는 스톱워치가 천천히 흘러 더 자주 차례가 온다.

## 핵심 용어 정리 (내부에 등장하는 것들)

스케줄링 공통 용어(선점·문맥 전환·I/O 바운드·응답 시간)는 004 용어표를 따르고, 여기서는 CFS 고유 용어만 세운다. 맨 위가 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 가상 런타임 vruntime (상위 키워드) | 가중치를 반영해 보정한 프로세스의 누적 실행 시간 | 스톱워치로 잰 누적 식사 시간 |
| 레드-블랙 트리 (Red-Black Tree) | vruntime 순으로 프로세스를 정렬해 두는 균형 이진 탐색 트리 | 식사 시간 적은 사람을 맨 왼쪽에 세운 줄 |
| 나이스 값 (Nice) | 프로세스 우선순위를 나타내는 값(-20~+19, 낮을수록 높은 우선순위) | 손님 등급표(VIP=-20) |
| 가중치 (Weight) | Nice 값을 CPU 배분 비율로 환산한 수치 | 등급에 따른 배식량 배율 |
| 타겟 레이턴시 (Target Latency) | 모든 프로세스가 한 번씩 실행되는 목표 주기 | 전원이 한 입씩 먹는 한 바퀴 시간 |
| min_granularity | 문맥 전환 남발을 막는 프로세스당 최소 실행 보장 시간 | "최소 한 입은 보장" 규칙 |
| O(1) 스케줄러 | CFS 이전의 리눅스 스케줄러, 배열 기반 상수 시간 선택 | 번호표 뽑아 순번대로 부르던 옛 방식 |
| 슬리퍼 보상 (Sleeper Compensation) | 오래 잔 프로세스의 vruntime을 트리 최소값 근처로 올려 독점 방지 | 늦게 온 사람이 첫 끼에 몰아 먹지 못하게 조정 |
| cgroups | 프로세스 그룹의 CPU·메모리를 제한하는 커널 기능 | 단체석별 총 배식량 상한 |

## 깊이 이해
- **배경·문제의식**: 004가 보인 스케줄러들은 퀀텀을 정적으로 계산하고 "대화형 여부"를 점수로 추측했다. 이 휴리스틱은 경계 사례마다 오작동하고 유지보수가 어렵다. CFS가 새로 던진 질문은 "**추측을 없애고 공평함을 수식 하나로 정의할 수 없을까**"이며, 리눅스 커널 2.6.23(2007)에 도입됐다.
- **작동 원리**:
  1. 레드-블랙 트리의 가장 왼쪽 노드(vruntime 최소)를 골라 실행한다.
  2. 실행한 실제 시간에 가중치 비율을 곱해 vruntime을 늘린 뒤 트리에 다시 넣는다.
  3. 우선순위가 높으면(가중치 큼) vruntime이 천천히 늘어 자주 왼쪽에 오고, 결과적으로 CPU를 더 받는다.
  4. 오래 잔 프로세스가 깨면 vruntime이 너무 작아 CPU를 독점할 수 있으므로, 트리의 min_vruntime 근처로 보정한다(슬리퍼 보상).
- **비유**: vruntime은 '지금까지 먹은 양'이다. 스케줄러는 언제나 가장 덜 먹은 사람에게 숟갈을 주므로 시간이 지나면 모두의 누적량이 평형을 이룬다. 우선순위(가중치)는 스톱워치 속도를 바꾸는 손잡이일 뿐, 규칙 자체는 하나다.
- **구체 예시(가중치 계산)**: A·B·C가 있고 타겟 레이턴시 30ms면 각 10ms씩 받는다. A의 우선순위(가중치)가 B의 2배면 A의 vruntime은 실제 시간의 절반 속도로 흐르므로, 같은 vruntime에 도달할 때까지 A가 약 2배 더 오래 실행된다. 즉 Nice 값이 CPU 점유 비율로 매끄럽게 환산된다.
- **흔한 오해·주의점**: CFS의 스케줄링 선택은 트리 삽입·삭제 때문에 O(log N)이라 O(1) 스케줄러보다 이론상 느리다. 그러나 캐시 지역성과 나노초 단위 정밀 제어로 실제 공평성·체감 성능이 더 낫다. 또 우선순위는 '큐 최상단 배치'가 아니라 'vruntime 증가 속도'로 반영된다는 점을 혼동하기 쉽다.

## 연결 개념
- 프로세스 스케줄링(004): CFS가 대체한 고전·휴리스틱 스케줄러의 한계.
- MLFQ(005): CFS가 걷어낸 다단계 큐·파라미터 튜닝 방식.
- 빅오 표기법: 트리 연산 O(log N)이 CFS 선택 비용의 근거.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CFS는 다중 큐·고정 퀀텀 없이 vruntime을 레드-블랙 트리로 관리해 수학적 공평성을 달성하는 리눅스 표준 스케줄러임.
> 2. **가치**: 대화형 판별용 자의적 휴리스틱을 제거하고 나노초 단위 정밀 스케줄링과 부하 무관한 일관성을 구현함.
> 3. **판단 포인트**: 우선순위(Nice)를 퀀텀 크기가 아닌 vruntime 증가 속도(가중치)로 반영해 불공평·우선순위 역전을 근본 차단함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 리눅스 현대 스케줄링 구조 이해 | vruntime, 레드-블랙 트리, 타겟 레이턴시 | O(1) 스케줄러(배열)와 혼동 |
| 우선순위·공평성 구현 메커니즘 | Nice→가중치→vruntime 증가율 반비례 | "우선순위 높으면 큐 최상단" 식 서술 |
| I/O 바운드·독점 방지 방안 | 슬리퍼 보상(min_vruntime 근처 보정) | 독점 방어 기법 누락 |

> 요약: 큐 대신 트리, 휴리스틱 대신 vruntime 계산으로 완전 공정 분배를 구현함.

## Ⅰ. 개요 및 필요성

- 개요: 모든 프로세스가 이상적 멀티태스킹 CPU를 공평하게 공유하는 모델을 근사한 리눅스 스케줄러임
- 위치: (004 스케줄링의 리눅스 표준 구현) O(1) 스케줄러의 휴리스틱 한계를 대체한 후속 세대임
- 필요성: 단순·수학적 모델로 부하와 무관하게 일관된 응답성과 나노초 정밀도를 보장함

## Ⅱ. 구조 및 구성요소

선형 구조도 (트리 최좌측 = 다음 선택):

    레드-블랙 트리 (Run Queue)
        루트(vruntime=100)
        /              \
    좌측(vruntime=50)   우측(vruntime=150)
    최소값 -> 다음 실행 대상

| 구성요소 | 역할 | 연산 기준 |
|:---|:---|:---|
| vruntime | CPU 점유 누적을 가중치로 보정한 가상 시간 | 실제시간 × (기준 가중치 / 프로세스 가중치) |
| 가중치(Weight) | Nice 값을 CPU 배분 비율로 환산 | Nice 낮을수록 가중치·점유 증가 |
| 레드-블랙 트리 | vruntime 기준 정렬·보관 | 삽입·삭제 O(log N) |
| 타겟 레이턴시 | 전원이 1회 실행되는 목표 주기 | 프로세스 수에 비례해 동적 조정 |

> 요약: 트리 최좌측(최소 vruntime)을 선택하며, 우선순위 높은 프로세스는 vruntime이 느리게 늘어 더 자주 선택됨.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도:

    트리 최좌측 노드(min vruntime) 선택 -> CPU 할당
      -> 나노초 단위 실제 실행 시간 누적
      -> 가중치 반영해 vruntime 갱신
      -> 갱신 위치로 트리에 재삽입

- 1단계 [선택]: 레드-블랙 트리 최좌측, 즉 vruntime이 가장 작은 프로세스를 선택함
- 2단계 [실행·측정]: 동적 타임 슬라이스(타겟 레이턴시 / 프로세스 수)만큼 실행 후 실제 시간을 나노초 단위로 측정함
- 3단계 [갱신]: 측정 실행 시간에 가중치 비율을 곱해 vruntime을 증가시킴
- 4단계 [재정렬]: 증가된 vruntime 위치로 프로세스를 트리에 재삽입함

> 요약: vruntime이 가장 작은 프로세스에 CPU를 몰아주어 전체 누적 실행량의 평형(공평성)을 맞춤.

## Ⅳ. 특징

- 동적 타임 슬라이스: 고정 퀀텀을 버리고 프로세스 수·타겟 레이턴시로 할당 시간을 동적 분배함
- 휴리스틱 최소화: I/O 바운드 추측 로직 없이 vruntime 단일 지표로 결정함
- 최소 보장 시간: min_granularity로 프로세스당 최소 실행을 보장해 문맥 전환 남발을 막음
- 연산 비용: 스케줄링 결정 자체는 트리 연산으로 O(log N)이며, 캐시 이점으로 실측 성능을 상쇄함

## Ⅴ. 심화 비교 및 적용 판단

CFS가 직접 대체한 직전 세대 O(1) 스케줄러와 대조함.

| 구분 | O(1) 스케줄러 | CFS |
|:---|:---|:---|
| 자료구조 | Active/Expired 배열 | 레드-블랙 트리 |
| 선택 비용 | O(1) | O(log N) |
| 응답성 판별 | 대화형 휴리스틱 점수 | vruntime 단일 지표 |
| 타임 슬라이스 | 고정 퀀텀 | 타겟 레이턴시 기반 동적 |

> 요약: O(log N) 페널티에도 휴리스틱 제거와 공평성 이점이 커 현대 범용 OS의 표준으로 자리 잡음.

**리스크·대응:**
- 슬리퍼 보상 악용: 장기 대기 후 깬 프로세스의 vruntime이 지나치게 작아 독점 → 깰 때 min_vruntime 근처로 보정
- 멀티코어 불균형: 특정 코어 트리에 부하 집중 → 로드 밸런서가 코어 간 vruntime 차를 감시해 프로세스 마이그레이션
- 실시간성 부족: 초저지연 작업이 공평 분배에 밀림 → RT 클래스(SCHED_FIFO)로 명시 분리

**점검 지표:**
- 성능: 스케줄링 지연(Scheduling Latency), 프로세스 마이그레이션 횟수
- 운영: Run Queue 크기, perf sched 프로파일링 결과

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. cgroups 연계 제어: 컨테이너 환경에서 CFS Bandwidth Control(quota/period)로 그룹별 CPU를 하드 리밋함
2. 스케줄링 클래스 분리: 완전한 실시간 보장이 필요한 작업은 CFS를 우회해 RT 클래스로 분리함
3. 튜닝 파라미터 조정: sched_latency_ns·sched_min_granularity_ns를 응답성 중시 환경에 맞춰 조정함

**결론:**
- 기술사 판단: CFS는 가상 시간 개념으로 공평성·성능 난제를 정연하게 풀었으나 초저지연 요구에는 RT 제어를 병행해야 함
- 향후 방향: 클라우드 네이티브에서 커널 수정 없이 정책을 주입하는 eBPF 스케줄러(sched_ext)가 대안으로 부상함
