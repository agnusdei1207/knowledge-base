## 미리 알고가기

- 상호 배제: 한 시점에 하나의 실행 주체만 임계 구역에 들어가게 하는 성질임
- 소유권: 락을 획득한 스레드만 해당 락을 해제할 수 있는 규칙임
- 조건 변수: 모니터 안에서 조건을 기다리고 신호로 깨우는 동기화 객체임

## 작성 근거(검토용)

- 뮤텍스·세마포어·모니터를 소유권·상태값·대기 조건·해제 주체·적용 대상으로 비교함
- 세 기법의 진입·대기·해제 의미가 달라 공통 흐름으로 뭉치지 않고 별도 흐름으로 나눔
- 서버 사례는 단일 공유 상태와 복수 자원 한도라는 대표 적용을 분리함

## Ⅰ. 개요
- **정의/개념**: 뮤텍스·세마포어·모니터는 공유 자원의 진입 조건과 대기·해제 규칙을 정의하는 동기화 기법임
- **배경/필요성**: 여러 스레드의 동시 갱신으로 생기는 경쟁 조건을 방지하기 위해 상호 배제와 자원 수 제어가 필요함

## Ⅱ. 특징

- 뮤텍스는 락 소유권을 가지며 획득한 스레드가 해제함
- 세마포어는 정수 카운터로 동시에 사용할 수 있는 자원 수를 제한함
- 모니터는 공유 상태·메서드·조건 변수를 언어 수준에서 캡슐화함
- 잘못된 획득 순서와 해제 누락은 교착상태·장기 대기를 발생시킬 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 뮤텍스 | 세마포어 | 모니터 |
|:---|:---|:---|:---|
| 제어 대상 | 단일 임계 구역 | 복수 자원·실행 허용 수 | 객체 내부 공유 상태 |
| 상태값 | 잠금·해제 | 0 이상의 정수 카운터 | 잠금 상태·조건 큐 |
| 소유권 | 있음 | 없음 | 모니터 진입 스레드 |
| 대기 조건 | 락 사용 중 | 카운터가 0 | 조건식이 거짓 |
| 해제·통지 | 소유자가 unlock | signal로 카운터 증가 | 메서드 종료·조건 signal |
| 대표 적용 사례 | 공유 자료구조 보호 | 연결 풀·동시 실행 수 제한 | 언어 객체 동기화 |

> 요약: 뮤텍스는 소유권, 세마포어는 자원 카운터, 모니터는 공유 상태와 조건 변수를 기준으로 동시 접근을 제어함.

## Ⅳ. 구성요소 및 구조
```
[ Mutex ] : Lock/Unlock (Owner exists)
[ Semaphore ] : Wait(P)/Signal(V) (Counter based)
[ Monitor ] : Shared Var + Procedures (Language level)
```
| 구성요소 | 설명 | 구분 기준 |
| :--- | :--- | :--- |
| 뮤텍스 | 0 또는 1의 값을 가지며, 락을 건 스레드만 해제 가능 | 소유권 |
| 세마포어 | 정수 값을 가지며, 여러 개 자원 관리 가능 (Signal/Wait) | 자원 개수 |
| 모니터 | 프로그래밍 언어 차원에서 제공하는 고수준 동기화 객체 | 조건 변수와 캡슐화 |
> 요약: 뮤텍스는 소유권, 세마포어는 개수, 모니터는 언어 수준 캡슐화가 기준임.

## Ⅴ. 원리 및 절차 흐름도
```
[뮤텍스] lock 요청 -> 소유권 획득 또는 대기 -> 임계 구역 -> 소유자 unlock
[세마포어] wait -> 카운터 감소 또는 대기 -> 자원 사용 -> signal
[모니터] 메서드 진입 -> 조건 검사·wait -> 상태 갱신 -> signal·퇴장
```
1. **뮤텍스**: 소유권을 얻은 스레드만 임계 구역에 진입하고 작업 후 락을 해제함
2. **세마포어**: 카운터가 양수이면 감소 후 진입하고 반환 시 signal로 카운터를 늘림
3. **모니터**: 메서드 진입 후 조건을 검사하고 wait·signal로 조건 큐를 제어함
> 요약: 각 기법은 소유권·카운터·조건 큐에 따라 진입과 해제 규칙이 달라짐.

## Ⅵ. 실무 사례

1. 공유 캐시 서버는 뮤텍스로 갱신 구역을 보호하고 락 대기시간과 경쟁 조건 발생 수를 확인함
2. DB 연결 풀은 세마포어로 동시 대여 수를 제한하고 연결 대기시간과 카운터 포화율을 확인함

## Ⅶ. 결론

- 동기화 기법은 공유 상태의 소유권과 동시 사용 가능한 자원 수·조건 대기 요구로 선택함
