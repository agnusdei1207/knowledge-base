## Ⅰ. 개요
- 정의: 공유 자원에 대한 동시 접근을 제어하여 데이터 일관성을 유지하기 위한 동기화 도구들
- 배경: 멀티스레드/프로세스 환경에서 경쟁 조건(Race Condition)을 방지하고 상호 배제 달성 필요
- 출제 의도: 각 도구의 소유권, 카운터, 언어 지원 수준 차이 비교

## Ⅱ. 구성요소
```
[ Mutex ] : Lock/Unlock (Owner exists)
[ Semaphore ] : Wait(P)/Signal(V) (Counter based)
[ Monitor ] : Shared Var + Procedures (Language level)
```
| 구성요소 | 설명 | 구분 기준 |
| :--- | :--- | :--- |
| 뮤텍스 | 0 또는 1의 값을 가지며, 락을 건 스레드만 해제 가능 | 소유권 |
| 세마포어 | 정수 값을 가지며, 여러 개 자원 관리 가능 (Signal/Wait) | 자원 개수 |
| 모니터 | 프로그래밍 언어 차원에서 제공하는 고수준 동기화 객체 | 조건 변수와 캡슐화 |
> 요약: 뮤텍스는 소유권, 세마포어는 개수, 모니터는 언어 수준 캡슐화가 기준임.

## Ⅲ. 절차
```
[Request] -> [Check Primitive] -> [Enter Critical Section] -> [Release]
```
1. 스레드가 공유 자원 접근을 위해 동기화 프리미티브(Lock 또는 P연산) 호출
2. 뮤텍스는 락 획득 시 진입, 세마포어는 카운터 감소(S>0) 시 진입
3. 임계 구역 내의 로직을 안전하게 수행하여 데이터 갱신 완료
4. 작업 종료 후 unlock 또는 V 연산으로 락·자원을 반환하고 대기 스레드의 실행 조건을 충족함
> 요약: 동기화 기법은 공유 자원의 진입 조건과 반환 순서를 정의해 동시 갱신을 통제함.

## Ⅳ. 문제점
- 원인: 프로그래머의 실수로 인한 세마포어 연산 누락 시 교착상태(Deadlock) 발생 위험
- 원인: 뮤텍스/세마포어의 잦은 호출은 커널 모드 전환에 따른 성능 오버헤드 유발

## Ⅴ. 개선방안
- (단기) 모니터와 같이 실수를 줄일 수 있는 고수준 언어 도구(Java synchronized 등) 활용
- (중기) 우선순위 역전 현상 방지를 위한 우선순위 상속(Priority Inheritance) 프로토콜 적용
- (장기) 무잠금(Lock-free) 또는 대기 없는(Wait-free) 알고리즘 및 CAS 연산 활용 확대

## Ⅵ. 전망
- 하드웨어 트랜잭셔널 메모리(HTM)의 보급으로 복잡한 소프트웨어 잠금 로직이 간소화될 것임
- 분산 시스템 동기화를 위한 Raft, Paxos 알고리즘과 연계된 분산 락 서비스(Zookeeper 등) 활용 증대

## 작성 근거(검토용)

- 동기화 프리미티브는 예시보다 소유권, 자원 개수, 언어 수준 캡슐화로 구분해야 비교 답안에 바로 쓸 수 있음
- 뮤텍스, 세마포어, 모니터의 차이가 표와 요약에서 같은 축으로 반복되도록 단어를 맞춤
