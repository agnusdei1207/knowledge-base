# 📖 【암기용】 개념 완전 이해

> 목적: Low-Code·No-Code 플랫폼을 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 시각적 모델링, 템플릿, 워크플로, 커넥터로 애플리케이션을 빠르게 만드는 플랫폼
- **왜 필요한가**: 현업 요구는 많고 개발 인력은 제한적이다. 단순 승인, 조회, 입력 업무는 전문 개발자가 모든 화면과 로직을 작성하지 않아도 된다.
- **핵심 직관**: 레고 블록처럼 화면, 데이터, 업무 흐름을 조립하되, 건물 허가와 전기 안전 기준은 별도로 지키는 방식이다.

## 깊이 이해
- **배경·문제의식**: 기업은 부서별 업무 앱, 승인 워크플로, 데이터 입력 화면을 계속 요구한다. 전통 개발만으로 처리하면 대기열이 길어지고, 현업은 엑셀·메일로 우회 시스템을 만든다.
- **작동 원리**: 플랫폼은 폼, 데이터 모델, 워크플로, API 커넥터, 권한 기능을 제공한다. 사용자는 드래그 앤드 드롭 또는 선언형 설정으로 앱을 만들고, 필요 시 개발자가 확장 코드를 추가한다.
- **비유**: 식당 주방을 새로 짓는 대신, 검증된 모듈형 조리대와 조리 도구를 배치해 메뉴를 만드는 것과 같다.
- **구체 예시**: 휴가 신청 앱은 직원 테이블, 신청 폼, 팀장 승인, 인사팀 알림, 권한 정책을 조합해 2주 내 파일럿을 만들 수 있다.
- **흔한 오해·주의점**: No-Code가 IT 거버넌스 부재를 뜻하지 않는다. 데이터 접근권한, 배포 승인, API 사용량, 앱 소유자 관리가 없으면 Shadow IT가 된다.

## 연결 개념
- Citizen Developer - 현업 사용자가 앱 제작에 참여
- BPM/Workflow - 승인·처리 절차 자동화
- API Management - 커넥터와 외부 연계 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: Low-Code·No-Code는 개발 생산성 논의가 아니라 거버넌스, 확장성, 보안 통제를 포함한 애플리케이션 공급 모델이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Low-Code·No-Code 플랫폼은 시각적 모델링과 재사용 컴포넌트로 업무 앱과 워크플로를 구성하는 개발 플랫폼이다.
> 2. **가치**: 단순 업무 앱의 개발 리드타임을 8주에서 2주 수준으로 줄이고, IT는 표준 커넥터와 권한 정책을 통제한다.
> 3. **판단 포인트**: 업무 복잡도, 사용자 수, 데이터 민감도, 커스텀 코드 비율, 벤더 종속성을 기준으로 적용 범위를 정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 플랫폼 개발 방식 이해 확인 | 모델러, 워크플로, 커넥터, 권한, 배포 | 화면 제작 도구 설명으로 축소 |
| 현업 개발 거버넌스 확인 | Citizen Developer, 승인, 표준 템플릿 | 무통제 Shadow IT 누락 |
| 적용 판단 확인 | 단순 앱 vs 복잡 트랜잭션, 벤더 종속 | 모든 시스템 대체 가능으로 서술 |

> 요약: 이 문제는 빠른 개발보다 통제된 현업 참여와 적용 경계 설정을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: Low-Code·No-Code는 시각적 조립 방식 앱 개발 플랫폼이다.
- 배경: 현업 요구 증가와 개발 인력 부족으로 단순 업무 앱의 개발 대기 시간이 커지고 있다.
- 필요성: 표준 컴포넌트, 권한, 배포 승인, 데이터 접근 정책으로 현업 개발과 IT 통제를 함께 적용해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Business Requirement -> Visual Modeler -> Data Model/Workflow
                     -> Connector/API -> Security/Policy -> App Release
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 시각 모델러 | 화면, 폼, 로직을 선언형으로 구성 | 복잡 알고리즘은 한계 |
| 워크플로 엔진 | 승인, 알림, 상태 전이를 처리 | SLA와 예외 경로 정의 |
| 커넥터/API | ERP, CRM, DB, SaaS 연계 | API 사용량과 권한 통제 |
| 거버넌스 계층 | 템플릿, 배포 승인, 접근권한 관리 | 앱 소유자 등록 필요 |

> 요약: 플랫폼은 화면 조립뿐 아니라 데이터, 워크플로, 연계, 정책 계층으로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항 접수 -> 앱 모델링 -> 데이터/권한 설정 -> 커넥터 연결
-> 테스트/승인 -> 배포 -> 사용량·오류 모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 요구와 데이터 등급 식별 | 개인정보·중요정보 분류 |
| 2 | 화면·흐름·권한 모델링 | 역할 기반 접근통제 적용 |
| 3 | 테스트와 배포 승인 | 핵심 시나리오 20건 이상 검증 |
| 4 | 운영 모니터링 | 오류율, API 호출량, 앱 소유자 점검 |

> 요약: Low-Code·No-Code는 모델링 후 배포 승인과 운영 모니터링까지 포함해야 한다.

## Ⅳ. 특징

| 구분 | 전통 개발 | Low-Code·No-Code | 판단 포인트 |
|:---|:---|:---|:---|
| 개발 방식 | 코드 중심 | 시각 모델·컴포넌트 조립 | 단순 CRUD·승인 업무 |
| 참여자 | 개발자 중심 | 현업+IT 공동 | Citizen Developer 교육 |
| 통제 | SDLC 도구 | 플랫폼 정책·템플릿 | 배포 승인·권한 관리 |
| 한계 | 개발 리드타임 증가 | 복잡 로직·벤더 종속 | 커스텀 코드 20% 이하 |

> 요약: 단순 업무 앱은 Low-Code·No-Code, 핵심 거래·복잡 알고리즘은 전통 개발을 선택한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | Spring/React 직접 개발 | 플랫폼 모델 기반 개발 | CRUD·승인·대시보드 중심 |
| 비용/성능 | 전문 개발 투입 | 라이선스+현업 개발 | 50명 이하 부서 앱 파일럿 |
| 운영/위험 | 코드 자유도 큼 | 벤더 종속·Shadow IT | 앱 카탈로그 100% 등록 |

> 요약: 적용 범위는 업무 복잡도와 거버넌스 수준으로 정해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Shadow IT | 무승인 앱 생성 | 앱 카탈로그, 배포 승인 | 미등록 앱 0건 |
| 데이터 노출 | 현업 권한 오설정 | RBAC, DLP, 감사 로그 | 권한 위반 0건 |
| 벤더 종속 | 독자 포맷·커넥터 | export 정책, API 우선 설계 | 탈출 계획 문서화 |

> 요약: Low-Code·No-Code는 속도보다 앱 등록, 권한, 벤더 종속 통제가 선행되어야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 개발 리드타임 | 단순 앱 2주 이하 | 요청-배포 이력 |
| 운영 품질 | 월 오류율 1% 이하 | 플랫폼 로그 |
| 거버넌스 | 앱 소유자·권한 100% 등록 | 앱 카탈로그 점검 |

> 요약: 도입 효과는 리드타임, 오류율, 앱 등록률로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 대상 선정: CRUD, 승인, 조회, 대시보드 업무를 1차 범위로 두고 핵심 거래·대량 배치 업무는 제외
2. 거버넌스 수립: 앱 소유자, 데이터 등급, 배포 승인, RBAC, 감사 로그를 플랫폼 표준으로 강제
3. 운영 전환: 사용량, 오류율, 커스텀 코드 비율 20% 초과 앱은 전문 개발 또는 API 기반 재구축 후보로 전환

**결론 (2줄):**
- 기술사 판단: 현업 단순 앱은 Low-Code·No-Code, 핵심 업무와 복잡 트랜잭션은 전통 개발 또는 하이브리드 개발을 선택함
- 향후 방향: 플랫폼은 AI 코드 생성, 업무 프로세스 마이닝, API 관리와 결합해 기업 앱 공급 체계로 발전함
