## Ⅰ. 개요
- 정의: Static vs Dynamic Analysis의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  +----------+      +----------+
  | Source   | ---> | Static   | (Review/Inspection)
  | Code     |      | Analysis |
  +----------+      +----------+
       |                 |
       v                 v
  +----------+      +----------+
  | Execution| ---> | Dynamic  | (Execution/Testing)
  | Trace    |      | Analysis |
  +----------+      +----------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 정적 분석 | 코드 실행 없이 구조/흐름 분석 | 설계도 검토 |
| 동적 분석 | 실제 실행을 통한 결함/성능 확인 | 시운전 |
| 도구 활용 | SonarQube, Valgrind 등 자동화 | 탐지기 |

> 요약: 실행 유무에 따른 상호 보완적 분석 기법임.

## Ⅲ. 절차
- ASCII 흐름도
  Target -> [Static Analysis] -> [Fix] -> [Dynamic Analysis] -> Result

1. 정적 도구 설정: 코딩 표준 및 룰셋 정의함.
2. 정적 검사 수행: 컴파일 전 잠재 결함 식별함.
3. 동적 환경 구성: 테스트 데이터 및 환경 구축함.
4. 동적 테스트: 시나리오 기반 실제 동작 검증함.

> 요약: 정적 분석 후 동적 분석을 통한 단계적 검증임.

## Ⅳ. 문제점
- 정적 분석 시 오탐(False Positive) 발생으로 검토 비용 증가함.
- 동적 분석 시 모든 경로(Path) 수행을 위한 비용 및 시간 과다함.

## Ⅴ. 개선방안
- AI 기반 오탐 필터링 및 룰셋 최적화로 정밀도 향상함.
- 테스트 커버리지 도구 연동 및 우선순위 기반 선별 테스트 수행함.

## Ⅵ. 전망
- LLM 기반 코드 리뷰 자동화와 연계하여 정적 분석 효율 극대화 예상됨.
- CSF: 지속적 통합(CI) 파이프라인 내 분석 자동화 및 품질 게이트(Quality Gate) 설정임.
