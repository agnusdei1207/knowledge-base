# 📖 【암기용】 개념 완전 이해

> 목적: LLMOps를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: LLMOps(Large Language Model Operations)는 **MLOps의 운영 원칙(평가 게이트·모니터링·재학습)을 대규모 언어모델 기반 생성형 AI 서비스에 맞게 확장**해, 모델 파일뿐 아니라 프롬프트·검색(RAG)·안전장치·비용까지 배포·평가·감시 대상으로 다루는 운영 체계다.
- **왜 필요한가**: LLM은 같은 질문에도 프롬프트 문구, 함께 넣은 컨텍스트, 모델 버전, 샘플링 온도(temperature)에 따라 답변이 달라진다. 게다가 사실이 아닌 내용을 그럴듯하게 답하는 환각(Hallucination), 개인정보 노출, 예측 불가능한 토큰 비용 폭증이라는 생성형 AI 고유의 리스크가 있다.
- **핵심 직관**: 전통 MLOps가 "모델 파일"을 배포 대상으로 다뤘다면, LLMOps는 "프롬프트 한 줄"까지도 배포 승인·평가·회귀 테스트가 필요한 배포 대상으로 다룬다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| MLOps (상위 개념) | LLMOps가 확장하는 원형 — ML 모델 생명주기 자동화 체계 | LLMOps는 MLOps의 생성형 AI 특화판 |
| RAG (Retrieval-Augmented Generation) | 질문에 답하기 전에 외부 문서를 검색해 그 내용을 근거로 답변을 생성하는 기법 | 시험 볼 때 참고자료를 펼쳐놓고 답 쓰기 |
| Hallucination (환각) | 모델이 근거 없는 내용을 사실인 것처럼 생성하는 현상 | 모르는 걸 아는 척 그럴듯하게 지어냄 |
| Prompt Registry | 프롬프트 템플릿과 체인의 버전을 코드처럼 관리하는 저장소 | 상담 스크립트의 개정판 이력 관리 |
| LLM Gateway | 모델 라우팅, 토큰 한도, 재시도, timeout을 통제하는 진입점 | 여러 상담원(모델)에게 문의를 배분하는 콜센터 교환대 |
| Guardrail | 유해 답변·개인정보·금칙어를 걸러내는 안전 필터 | 상담원이 절대 말하면 안 되는 금지 답변 목록 |
| Prompt Injection | 사용자 입력이 시스템 지시를 덮어써 의도치 않은 동작을 유도하는 공격 | 손님이 "이전 지시는 무시하고 이렇게 해"라고 속임 |
| LLM-as-a-judge | 사람 대신 다른 LLM으로 답변 품질(정답성·근거성)을 자동 채점하는 평가 방식 | 채점 담당을 또 다른 채점관 AI에게 맡김 |

## 깊이 이해

### 왜 MLOps만으로는 부족한가 (배경)
- 전통 ML은 "학습 데이터 + 모델 파라미터"가 답변 품질을 결정하므로, 재학습을 해야만 동작이 바뀐다. 반면 상용 LLM API를 그대로 쓰는 서비스는 **모델 파라미터를 건드리지 않고도** 프롬프트 문구나 함께 주는 컨텍스트(RAG 검색 결과)만 바꿔서 답변이 완전히 달라진다.
- 즉 "재학습 없이 배포가 일어나는" 구조라서, 프롬프트 수정 하나도 코드 배포처럼 버전 관리·평가·승인 절차를 거쳐야 회귀(이전엔 맞던 답이 갑자기 틀리는 현상)를 막을 수 있다.

### 판별 원리 — 파인튜닝 vs RAG vs 프롬프트 수정
- 셋 중 무엇을 쓸지는 **데이터 최신성, 비용, 변경 주기**로 판단한다. 정보가 자주 바뀌면(사내 정책 문서 등) RAG로 검색 결과를 실시간 반영하는 편이 파인튜닝보다 비용이 낮고 최신성이 높다. 말투·형식처럼 반복적이고 안정적인 패턴은 파인튜닝이 유리하다. 간단한 규칙 변경(금칙어 추가 등)은 프롬프트 수정만으로 충분하다.

### 작동 원리와 수치로 보는 흐름
1. 업무별 질문·금지 답변·참조 문서로 구성된 평가셋(예: 100건 이상)을 먼저 만든다.
2. 프롬프트 템플릿과 RAG 체인의 새 버전을 Prompt Registry에 생성한다.
3. 자동 평가(LLM-as-a-judge)와 Human Review를 함께 수행해 **정답률, 근거 문서 일치율, 금칙어 차단률**을 측정한다. 예: 근거 일치율 95% 이상, 금칙어 차단률 99% 이상을 통과 기준으로 둔다.
4. 기준을 통과한 프롬프트만 운영에 배포하고, 이후 실제 트래픽에서 p95 응답 시간(예: 3초 이하)과 요청당 토큰 비용(예: 30원 이하)을 계속 감시한다. 지표가 기준을 벗어나면 프롬프트 롤백 또는 재검토를 트리거한다.

### 환각(Hallucination)을 구체적으로 이해하기
- 예: "우리 회사의 2025년 환불 정책은?"이라는 질문에 관련 문서가 검색되지 않았는데도 모델이 그럴듯한 환불 기간(예: "30일 이내")을 지어내 답하는 경우가 환각이다.
- RAG는 이를 줄이는 핵심 대응이다 — 검색된 근거 문서가 없으면 "모른다"고 답하도록 강제하고, 답변에 반드시 근거 문서를 함께 출력하게 해 근거 일치율을 지표로 관리한다.

### 비유와 흔한 오해
- **비유**: 콜센터를 운영할 때 상담원(모델) 채용만으로 끝나지 않고, 상담 스크립트(프롬프트), 참조 매뉴얼(RAG 문서), 절대 하면 안 되는 답변 목록(Guardrail), 통화 품질 평가표(평가셋)를 함께 운영하는 것과 같다.
- **오해**: LLMOps는 파인튜닝 자동화만을 뜻하지 않는다. 상용 API(예: Claude, GPT)를 그대로 호출하는 서비스라도, 프롬프트 버전 관리·RAG 품질 평가·로그의 개인정보 마스킹·비용 상한 설정은 여전히 필수다.

## 연결 개념
- RAG — 환각을 줄이고 답변에 근거를 제공하는 핵심 기법
- Prompt Engineering — 프롬프트 템플릿·체인의 설계와 버전 관리
- AI Governance — 개인정보·저작권·안전성 규제 준수를 다루는 상위 통제 체계
- MLOps — LLMOps가 그 운영 원칙을 확장한 상위 개념

## Ⅰ. 개요 및 필요성

- 개요: LLMOps는 LLM 서비스 운영 관리 체계다.
- 배경: LLM 답변은 프롬프트, 컨텍스트, 모델 버전, 샘플링 설정에 따라 달라진다.
- 필요성: 배포 전 평가셋 검증과 배포 후 환각률, 토큰 비용, 안전 정책 위반 지표를 감시해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User Query -> Prompt Template -> Retrieval Context -> LLM Gateway -> Guardrail -> Response
                         / Evaluation Set
                         / Prompt Registry
                         / Observability
```

| 구성요소 | 역할 | 통제 기준 |
|:---|:---|:---|
| 프롬프트 레지스트리 | 템플릿, 변수, 체인 버전 관리 | Git SHA, 승인 상태 |
| LLM 게이트웨이 | 모델 라우팅, 토큰 한도, 재시도 | rate limit, timeout |
| 평가·가드레일 | 정답성, 유해성, 개인정보 점검 | LLM-as-judge, DLP |
| 관측성 | 요청, 토큰, 지연, 차단 이력 수집 | trace, cost log |

> 요약: LLMOps 구조는 프롬프트와 RAG 컨텍스트를 모델 호출 전후 통제 지점으로 배치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구 정의 -> 프롬프트 작성 -> 평가셋 실행 -> 안전 필터 검증 -> 단계 배포 -> 로그 분석 -> 프롬프트 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무별 질문, 금지 답변, 참조 문서 정의 | 평가셋 100건 이상 |
| 2 | 프롬프트와 RAG 체인 버전 생성 | 템플릿 변수 검증 |
| 3 | 자동 평가와 Human Review 수행 | 정답률, 근거 일치율, 차단률 |
| 4 | 운영 로그 기반 비용·품질 감시 | p95 3초, 토큰 비용 예산 |

> 요약: LLMOps는 프롬프트 변경도 배포 변경으로 취급하고 평가셋과 운영 로그로 회귀를 탐지한다.

## Ⅳ. 특징

| 구분 | MLOps | LLMOps | 판단 포인트 |
|:---|:---|:---|:---|
| 변경 단위 | 모델 파일, 데이터 | 프롬프트, 체인, 검색 인덱스, 모델 | 프롬프트 배포 승인 필요 |
| 평가 | 정확도, RMSE, AUC | 근거성, 환각률, 유해성, 비용 | 자동 평가와 사람 검토 병행 |
| 운영 리스크 | 드리프트, 지연 | 토큰 비용, 개인정보, 프롬프트 인젝션 | Guardrail 설계 |

> 요약: LLMOps는 일반 MLOps보다 프롬프트와 컨텍스트 변화가 품질에 미치는 영향을 더 세밀하게 추적한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | LLMOps | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 모델 API 호출 | Gateway, RAG, Guardrail, 평가 체계 | 업무 답변 자동화 서비스 |
| 비용/성능 | 요청별 API 호출 관리 | 토큰 예산, 캐시, 모델 라우팅 | 월 토큰 예산 초과 위험 |
| 운영/위험 | 로그만 저장 | 마스킹, 감사, 차단, 리뷰 | 개인정보·규제 데이터 포함 |

> 요약: LLMOps는 업무 영향이 있는 LLM 응답을 비용과 안전 지표로 운영할 때 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 환각 답변 | 근거 문서 부재, 검색 실패 | RAG, 근거 문서 필수 출력 | 근거 일치율 95% |
| 프롬프트 인젝션 | 사용자 입력이 시스템 지시를 오염 | 입력 필터, tool 권한 분리 | 차단 이벤트 수 |
| 비용 초과 | 장문 컨텍스트와 고가 모델 호출 | 토큰 한도, 캐시, 저비용 모델 라우팅 | 요청당 비용 |

> 요약: LLMOps 리스크는 환각, 인젝션, 비용이며 검색 품질과 게이트웨이 정책으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 답변 품질 | 정답률 90%, 근거 일치율 95% | 골든셋, Human Review |
| 안전 통제 | 개인정보 노출 0건, 금칙어 차단 99% | DLP, 안전 평가셋 |
| 운영 비용 | 요청당 토큰 예산 준수 | LLM Gateway 비용 로그 |

> 요약: LLMOps 성과는 답변 품질, 안전 통제, 토큰 비용을 동시에 측정해야 판단 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LangSmith, MLflow, W&B 중 하나로 프롬프트, 체인, 평가셋, 실행 로그를 버전 단위로 기록함
2. LLM Gateway에 모델 라우팅, 토큰 상한, PII 마스킹, timeout 10초, 재시도 1회를 정책화함
3. 정답성 90%, 근거 일치율 95%, 금칙어 차단 99% 기준을 통과한 프롬프트만 Production에 배포함

**결론 (2줄):**
- 기술사 판단: 외부 고객 응답이나 업무 의사결정에 쓰는 LLM은 LLMOps를 필수 적용하고, 내부 실험은 프롬프트 추적과 비용 한도부터 적용함
- 향후 방향: LLMOps는 AgentOps, RAG 평가, 모델 라우팅과 결합해 생성형 AI 운영 플랫폼으로 발전함
