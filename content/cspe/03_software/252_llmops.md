# 📖 【암기용】 개념 완전 이해

> 목적: LLMOps를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: LLMOps는 대규모 언어모델 기반 서비스를 프롬프트, 검색, 평가, 배포, 감시 관점에서 운영하는 체계다.
- **왜 필요한가**: LLM 서비스는 같은 질문에도 프롬프트, 컨텍스트, 모델 버전, 온도 값에 따라 답변이 달라진다. 환각, 개인정보 노출, 비용 폭증도 운영 리스크다.
- **핵심 직관**: LLMOps는 모델 파일보다 프롬프트와 컨텍스트까지 배포 대상으로 다루는 생성형 AI 운영 방식이다.

## 깊이 이해
- **배경·문제의식**: 전통 ML은 학습 데이터와 모델 파라미터가 핵심이지만, LLM 서비스는 프롬프트 템플릿, RAG 검색 결과, 안전 필터, 토큰 비용이 품질을 좌우한다.
- **작동 원리**: 프롬프트와 체인 버전을 관리하고, 평가 데이터셋으로 정답성·근거성·금칙어를 검사한다. 배포 후 토큰 사용량, 지연, 환각률, 차단률을 감시한다.
- **비유**: 상담원을 고용하는 것보다 상담 스크립트, 참조 문서, 금지 답변, 통화 품질 평가표를 함께 운영하는 일에 가깝다.
- **구체 예시**: 고객센터 LLM은 답변 근거 문서 포함률 95%, 금칙어 차단률 99%, p95 응답 3초 이하, 1건당 토큰 비용 30원 이하를 목표로 운영한다.
- **흔한 오해·주의점**: LLMOps는 파인튜닝 자동화만 의미하지 않는다. 상용 API를 쓰는 경우에도 프롬프트 버전, RAG 평가, 로그 마스킹, 비용 한도는 필수다.

## 연결 개념
- RAG: 외부 지식 검색으로 답변 근거 확보
- Prompt Engineering: 프롬프트 템플릿과 체인 버전 관리
- AI Governance: 개인정보, 저작권, 안전성 통제

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: LLMOps 답안은 모델 배포보다 프롬프트, RAG, 평가, 비용, 안전 필터 운영을 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLMOps는 LLM 애플리케이션의 프롬프트, 컨텍스트, 모델, 평가, 안전장치, 비용을 운영 통제하는 체계다.
> 2. **가치**: 환각률, 근거 문서 일치율, 토큰 비용, p95 응답 지연을 지표화해 생성형 AI 품질을 반복 개선한다.
> 3. **판단 포인트**: 파인튜닝, RAG, 프롬프트 수정 중 어떤 수단을 쓸지 데이터 민감도, 비용, 변경 주기 기준으로 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 운영 특성 확인 | 프롬프트 버전, RAG, 평가셋, Guardrail | MLOps와 동일하게만 설명 |
| 품질 평가 역량 확인 | 정답성, 근거성, 유해성, 비용, 지연 | BLEU 같은 단일 지표로 축소 |
| 위험 통제 확인 | 개인정보 마스킹, 금칙어, 감사로그, Human Review | 환각을 모델 교체만으로 해결한다고 단정 |

> 요약: LLMOps는 생성 품질과 안전 리스크를 프롬프트·검색·평가·감시 체계로 통제하는 문제다.

## Ⅰ. 개요 및 필요성

- 개요: LLMOps는 LLM 서비스 운영 관리 체계다.
- 배경: LLM 답변은 프롬프트, 컨텍스트, 모델 버전, 샘플링 설정에 따라 달라진다.
- 필요성: 배포 전 평가셋 검증과 배포 후 환각률, 토큰 비용, 안전 정책 위반 지표를 감시해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User Query -> Prompt Template -> Retrieval Context -> LLM Gateway -> Guardrail -> Response
                         / Evaluation Set
                         / Prompt Registry
                         / Observability
```

| 구성요소 | 역할 | 통제 기준 |
|:---|:---|:---|
| 프롬프트 레지스트리 | 템플릿, 변수, 체인 버전 관리 | Git SHA, 승인 상태 |
| LLM 게이트웨이 | 모델 라우팅, 토큰 한도, 재시도 | rate limit, timeout |
| 평가·가드레일 | 정답성, 유해성, 개인정보 점검 | LLM-as-judge, DLP |
| 관측성 | 요청, 토큰, 지연, 차단 이력 수집 | trace, cost log |

> 요약: LLMOps 구조는 프롬프트와 RAG 컨텍스트를 모델 호출 전후 통제 지점으로 배치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구 정의 -> 프롬프트 작성 -> 평가셋 실행 -> 안전 필터 검증 -> 단계 배포 -> 로그 분석 -> 프롬프트 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무별 질문, 금지 답변, 참조 문서 정의 | 평가셋 100건 이상 |
| 2 | 프롬프트와 RAG 체인 버전 생성 | 템플릿 변수 검증 |
| 3 | 자동 평가와 Human Review 수행 | 정답률, 근거 일치율, 차단률 |
| 4 | 운영 로그 기반 비용·품질 감시 | p95 3초, 토큰 비용 예산 |

> 요약: LLMOps는 프롬프트 변경도 배포 변경으로 취급하고 평가셋과 운영 로그로 회귀를 탐지한다.

---

## Ⅳ. 특징

| 구분 | MLOps | LLMOps | 판단 포인트 |
|:---|:---|:---|:---|
| 변경 단위 | 모델 파일, 데이터 | 프롬프트, 체인, 검색 인덱스, 모델 | 프롬프트 배포 승인 필요 |
| 평가 | 정확도, RMSE, AUC | 근거성, 환각률, 유해성, 비용 | 자동 평가와 사람 검토 병행 |
| 운영 리스크 | 드리프트, 지연 | 토큰 비용, 개인정보, 프롬프트 인젝션 | Guardrail 설계 |

> 요약: LLMOps는 일반 MLOps보다 프롬프트와 컨텍스트 변화가 품질에 미치는 영향을 더 세밀하게 추적한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | LLMOps | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 모델 API 호출 | Gateway, RAG, Guardrail, 평가 체계 | 업무 답변 자동화 서비스 |
| 비용/성능 | 요청별 API 호출 관리 | 토큰 예산, 캐시, 모델 라우팅 | 월 토큰 예산 초과 위험 |
| 운영/위험 | 로그만 저장 | 마스킹, 감사, 차단, 리뷰 | 개인정보·규제 데이터 포함 |

> 요약: LLMOps는 업무 영향이 있는 LLM 응답을 비용과 안전 지표로 운영할 때 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 환각 답변 | 근거 문서 부재, 검색 실패 | RAG, 근거 문서 필수 출력 | 근거 일치율 95% |
| 프롬프트 인젝션 | 사용자 입력이 시스템 지시를 오염 | 입력 필터, tool 권한 분리 | 차단 이벤트 수 |
| 비용 초과 | 장문 컨텍스트와 고가 모델 호출 | 토큰 한도, 캐시, 저비용 모델 라우팅 | 요청당 비용 |

> 요약: LLMOps 리스크는 환각, 인젝션, 비용이며 검색 품질과 게이트웨이 정책으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 답변 품질 | 정답률 90%, 근거 일치율 95% | 골든셋, Human Review |
| 안전 통제 | 개인정보 노출 0건, 금칙어 차단 99% | DLP, 안전 평가셋 |
| 운영 비용 | 요청당 토큰 예산 준수 | LLM Gateway 비용 로그 |

> 요약: LLMOps 성과는 답변 품질, 안전 통제, 토큰 비용을 동시에 측정해야 판단 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LangSmith, MLflow, W&B 중 하나로 프롬프트, 체인, 평가셋, 실행 로그를 버전 단위로 기록함
2. LLM Gateway에 모델 라우팅, 토큰 상한, PII 마스킹, timeout 10초, 재시도 1회를 정책화함
3. 정답성 90%, 근거 일치율 95%, 금칙어 차단 99% 기준을 통과한 프롬프트만 Production에 배포함

**결론 (2줄):**
- 기술사 판단: 외부 고객 응답이나 업무 의사결정에 쓰는 LLM은 LLMOps를 필수 적용하고, 내부 실험은 프롬프트 추적과 비용 한도부터 적용함
- 향후 방향: LLMOps는 AgentOps, RAG 평가, 모델 라우팅과 결합해 생성형 AI 운영 플랫폼으로 발전함
