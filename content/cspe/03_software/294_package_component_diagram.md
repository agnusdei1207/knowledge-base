## Ⅰ. 개요
- 정의: 시스템을 구성하는 논리적/물리적 단위인 패키지와 컴포넌트의 구조를 정의함
- 배경: 대규모 시스템의 모듈화 및 재사용 가능한 독립 단위 관리 필요성 대두
- 출제 의도: 물리적 구현 단계의 모듈 설계 및 의존성 관리 전략 검증

## Ⅱ. 구성요소
- ASCII 구조도
  +----------+      +----------------+
  | PackageA |----->| <<Component>>  |--O [Interface]
  +----------+      |    Module B    |
                    +----------------+
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 패키지 | 관련된 요소를 그룹화하는 논리적 컨테이너 | 폴더/서류함 |
| 컴포넌트 | 실행 가능하고 교체 가능한 물리적 부품 단위 | PC 부품 |
| 인터페이스 | 컴포넌트 간 상호작용을 위한 서비스 접점 | USB 포트 |
> 요약: 논리적 그룹인 패키지와 물리적 교체 단위인 컴포넌트로 구조화함

## Ⅲ. 절차
- ASCII 흐름도
  Grouping -> Component ID -> Interface Def -> Dependency
- 4단계 설명
1. Grouping: 유사한 책임을 가진 클래스들을 패키지로 논리적 묶음 수행함
2. Component ID: 실행 시 독립적으로 배포 가능한 물리적 단위 정의함
3. Interface Def: 제공(Provided) 및 요구(Required) 인터페이스 정의함
4. Dependency: 컴포넌트 간의 결합 관계 및 의존 방향을 설정함
> 요약: 논리적 그룹화 후 물리적 컴포넌트와 그 접점인 인터페이스를 정의함

## Ⅳ. 문제점
- 패키지 간 순환 의존이 생기면 독립 컴파일·시험·배포 단위를 분리하기 어려움

## Ⅴ. 개선방안
- 의존 방향을 계층화하고 공통 인터페이스를 분리하여 비순환 의존 원칙을 적용함

## Ⅵ. 전망
- 발전 방향: 마이크로서비스(MSA) 환경의 컨테이너 단위 컴포넌트 설계 및 서비스 메쉬 연동
- CSF: 컴포넌트의 명확한 인터페이스 정의와 높은 독립성(Self-contained) 확보가 필수임
