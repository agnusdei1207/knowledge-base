## 미리 알고가기

- 실행 계획은 데이터베이스가 SQL을 실제로 수행하는 접근 경로와 조인 순서를 뜻함
- 옵티마이저는 통계 정보와 비용 추정을 바탕으로 여러 후보 중 한 계획을 고름
- 카디널리티 추정은 조건을 통과할 행 수를 예측하는 일이며 이 추정이 틀리면 좋은 인덱스가 있어도 나쁜 계획이 나올 수 있음

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 실행 계획은 통계·접근 경로·조인 순서·실측 결과를 핵심 축으로 설명함
- 비교표는 규칙 기반 접근과 비용 기반 최적화의 판단 근거를 대비함
- 운영 DB는 계획 회귀 건수·p95 질의 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 실행 계획 최적화는 통계와 비용을 기준으로 SQL의 접근 경로·조인 순서·연산자를 선택해 응답 지연과 자원 사용량을 줄이는 활동임
- **배경/필요성**: 데이터 분포와 통계 상태 변화에 따른 계획 회귀를 방지하기 위해 예상 비용과 실제 실행 결과를 비교해 접근 경로를 교정해야 함

## Ⅱ. 특징

- 옵티마이저는 통계와 비용 모델을 바탕으로 실행 계획을 자동 선택함
- scan·index 접근량, 조인 순서·알고리즘, sort·temporary I/O가 계획의 추정·실측 비용을 구성함
- SQL을 바꾸지 않아도 통계 갱신과 인덱스 조정만으로 성능이 달라질 수 있음
- 힌트를 고정 수단으로 남용하면 데이터 분포가 바뀐 뒤 오히려 장기 병목이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 규칙 기반 접근 | 비용 기반 최적화 |
|:---|:---|:---|
| 판단 방식 | 경험 규칙과 작성 습관을 중심으로 튜닝함 | 통계와 비용 추정을 바탕으로 계획을 선택함 |
| 판단 근거 | 경험 규칙과 알려진 반패턴 | 통계의 행 수·선택도와 CPU·I/O 비용 추정 |
| 한계 | 환경이 바뀌면 근거가 약해질 수 있음 | 통계가 틀리면 잘못된 계획을 고를 수 있음 |
| 실무 사용 방식 | SQL 재작성의 출발점으로 활용함 | 현대 데이터베이스 제품의 기본 최적화 방식으로 사용함 |

> 요약: 규칙 기반 접근은 경험 규칙으로 SQL을 교정하고, 비용 기반 최적화는 통계와 비용으로 실행 계획을 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 통계 정보 | 값 분포와 선택도를 기록해 비용 추정의 정확도를 좌우함 |
| 접근 경로 | 전체 스캔과 인덱스 스캔과 룩업 중 어떤 경로를 쓸지 정함 |
| 조인 순서와 연산자 | 어떤 테이블부터 결합하고 어떤 조인 방식을 쓸지 결정함 |
| 실행 결과 비교 | 예상 행 수와 실제 행 수를 비교해 계획 추정 오차의 원인을 식별함 |

> 요약: 통계 정보로 접근 경로와 조인 방식을 선택하고 예상 행 수와 실제 행 수의 차이로 계획 오류를 찾음.

## Ⅴ. 원리 및 절차 흐름도

1. **느린 쿼리 식별**: 지연이 큰 SQL과 자원 사용량을 찾음
2. **계획과 통계 분석**: 접근 경로와 조인 순서와 추정 오차를 확인함
3. **SQL과 인덱스 교정**: 쿼리 구조와 인덱스와 통계를 조정함
4. **재실행 검증**: 실제 성능 개선과 부작용을 다시 측정함

> 요약: 느린 SQL의 계획과 통계 오차를 분석해 SQL·인덱스·통계를 교정하고 실제 성능을 재검증함.

## Ⅵ. 실무 사례

1. 주문 DB는 예상·실제 행 수 차이로 통계와 인덱스를 교정하고 계획 회귀 건수·p95 지연을 확인함
2. 배치 DB는 조인 순서와 임시 작업을 분석하고 처리 시간·임시 파일 용량을 확인함

## Ⅶ. 결론

- 쿼리 최적화는 통계와 실측 결과로 실행 계획의 선택 근거를 확인하고 접근 경로를 교정하는 활동임
