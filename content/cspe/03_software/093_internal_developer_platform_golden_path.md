## 미리 알고가기

- 골든 패스는 조직이 권장하는 가장 쉬운 기본 개발 경로임
- 모든 자유를 막는 강제가 아니라 표준 성공 경로를 먼저 제공하는 설계 방식임
- 플랫폼 채택률과 우회 비율이 실효성을 판단하는 핵심 지표임

## Ⅰ. 개요

- **정의/개념**: 내부 개발자 플랫폼의 골든 패스는 신규 서비스 생성과 배포와 관측과 보안 기본값까지 포함한 권장 표준 경로를 제공해 대부분의 팀이 최소한의 의사결정으로 빠르게 올바른 개발 흐름을 따르도록 만드는 플랫폼 설계 방식임
- **배경/필요성**: 팀마다 다른 빌드와 배포와 운영 방식을 쓰면 품질 편차와 온보딩 비용이 커지므로, 자주 쓰는 성공 경로를 기본 제공해 표준화를 자연스럽게 유도할 필요가 있음

## Ⅱ. 특징

- 기본 경로를 쉽게 만들어 표준 채택을 강제보다 유도 중심으로 달성함
- 보안과 관측과 배포 규칙을 기본값으로 포함해 초기 품질을 높임
- 예외 경로가 필요한 팀을 위한 확장 포인트가 없으면 반발과 우회가 증가함
- 플랫폼 문서와 템플릿 유지 품질이 낮으면 골든 패스 자체가 사용되지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 자유 선택형 플랫폼 | 골든 패스 중심 플랫폼 |
|:---|:---|:---|
| 시작 속도 | 팀별 탐색 필요 | 즉시 시작 가능 |
| 표준화 수준 | 낮을 수 있음 | 높음 |
| 유연성 | 높음 | 확장 포인트 설계 필요 |
| 운영 효과 | 편차 큼 | 공통 운영 효율 확보 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Starter Template | 저장소 구조와 CI와 배포와 관측 기본값을 한 번에 제공함 |
| Opinionated Workflow | 조직이 권장하는 개발·배포 절차를 기본 흐름으로 내장함 |
| Extension Point | 특수 요구 팀이 표준을 유지하며 확장할 수 있게 경계를 제공함 |
| Usage Analytics | 실제 채택률과 이탈 구간을 측정해 골든 패스 개선 근거를 만듦 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기본 템플릿 선택 | --> | 표준 경로 실행   | --> | 예외 확장 적용  | --> | 사용성 개선     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기본 템플릿 선택**: 개발 팀이 권장 시작 구성을 선택함
2. **표준 경로 실행**: 빌드와 배포와 관측을 기본 워크플로우로 수행함
3. **예외 확장 적용**: 필요한 경우 허용된 확장 포인트만 사용함
4. **사용성 개선**: 이탈 구간과 요청 패턴을 반영해 경로를 다듬음

## Ⅵ. 문제점 및 해결 방안

1. 문제: 골든 패스가 현장 업무 흐름과 맞지 않으면 개발팀이 별도 스크립트와 파이프라인을 만들어 플랫폼 채택이 떨어질 수 있음
   - 해결방안: top user journey를 기준으로 템플릿을 설계하고 golden path completion rate와 bypass ratio로 검증함
2. 문제: 표준 경로에 예외 확장 포인트가 부족하면 특수 시스템이 플랫폼 밖으로 이탈할 수 있음
   - 해결방안: controlled extension model을 제공하고 extension success rate와 unsupported request count로 검증함
3. 문제: 문서와 템플릿이 오래되면 신규 팀 온보딩 속도가 다시 느려질 수 있음
   - 해결방안: template freshness review를 운영하고 onboarding lead time과 stale template ratio로 검증함

## Ⅶ. 적용 사례

- 사내 서비스 템플릿 플랫폼에서는 권장 경로를 제공하고 확인 지표는 golden path completion rate와 bypass ratio임
- 데이터 플랫폼 팀에서는 확장 포인트를 운영하고 확인 지표는 extension success rate와 unsupported request count임
- 신규 입사자 온보딩 프로그램에서는 템플릿 최신화를 관리하고 확인 지표는 onboarding lead time과 stale template ratio임

## Ⅷ. 결론

골든 패스는 개발자 선택을 없애는 체계가 아니라 가장 빈번한 성공 경로를 가장 쉽게 만들어 조직 표준을 자연스럽게 확산시키는 방식임.
