## 미리 알고가기

- 골든 패스는 조직이 권장하는 가장 쉬운 기본 개발 경로임
- 강제 경로가 아니라 표준 성공 경로를 기본값으로 제공하는 설계 방식임
- 우회 비율은 개발팀이 골든 패스를 쓰지 않고 별도 경로를 만드는 정도를 뜻함

## Ⅰ. 개요

- **정의/개념**: 내부 개발자 플랫폼의 골든 패스는 신규 서비스 생성과 배포와 관측과 보안 기본값까지 포함한 권장 표준 경로를 제공해 대부분의 팀이 최소한의 의사결정으로 빠르게 올바른 개발 흐름을 따르도록 만드는 플랫폼 설계 방식임.
- **배경/필요성**: 팀마다 다른 빌드와 배포와 운영 방식을 쓰면 품질 편차와 온보딩 비용이 커지므로, 자주 쓰는 성공 경로를 기본 제공해 표준화를 자연스럽게 유도할 필요가 있음.

## Ⅱ. 특징

- 가장 자주 쓰는 경로를 쉽게 만들어 표준 채택을 유도함
- 보안과 관측과 배포 규칙을 기본값으로 포함해 초기 품질을 높임
- 예외 경로를 위한 확장 포인트가 없으면 반발과 우회가 증가함
- 템플릿과 문서 품질이 낮으면 골든 패스 자체가 사용되지 않음

## Ⅲ. 종류 및 비교

| 구분 | 자유 선택형 플랫폼 | 골든 패스 중심 플랫폼 |
|:---|:---|:---|
| 시작 방식 | 팀이 필요한 도구와 절차를 직접 고름 | 권장 템플릿과 절차로 바로 시작함 |
| 얻는 장점 | 유연성이 높아 특수 요구 수용이 쉬움 | 빠른 시작과 높은 표준화 효과를 얻기 쉬움 |
| 주요 한계 | 팀별 편차와 운영 복잡도가 커지기 쉬움 | 확장 포인트 설계가 약하면 우회 사용이 늘 수 있음 |
| 적합한 상황 | 성격이 매우 다른 팀이 느슨하게 공존할 때 적합함 | 공통 서비스 패턴이 많은 조직에 적합함 |

> 요약: 골든 패스의 핵심은 개발자 자유를 없애는 것이 아니라 가장 많이 쓰는 성공 경로를 가장 쉽게 만드는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 시작 템플릿 | 저장소 구조와 배포와 관측 기본값을 한 번에 제공함 |
| 권장 워크플로우 | 조직이 권장하는 개발·배포 절차를 기본 흐름으로 내장함 |
| 확장 지점 | 특수 요구 팀이 표준을 유지하며 확장할 수 있게 경계를 제공함 |
| 사용 분석 | 실제 채택률과 이탈 구간을 측정해 골든 패스 개선 근거를 만듦 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기본 템플릿 선택 | --> | 표준 경로 실행   | --> | 예외 확장 적용  | --> | 사용성 개선     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기본 템플릿 선택**: 개발 팀이 권장 시작 구성을 선택함
2. **표준 경로 실행**: 빌드와 배포와 관측을 기본 워크플로우로 수행함
3. **예외 확장 적용**: 필요한 경우 허용된 확장 지점만 사용함
4. **사용성 개선**: 이탈 구간과 요청 패턴을 반영해 경로를 다듬음

## Ⅵ. 실무 적용 및 유의점

1. 사내 서비스 템플릿 플랫폼에서는 골든 패스가 온보딩 속도를 높이지만 실제 업무 흐름과 맞지 않으면 별도 스크립트가 늘어나므로 상위 사용자 여정을 기준으로 템플릿을 설계하고 골든 패스 완료율과 우회 비율로 확인함
2. 데이터 플랫폼이나 특수 시스템 팀처럼 예외 요구가 많은 조직에서는 확장 지점이 부족하면 플랫폼 밖으로 이탈하므로 통제된 확장 모델을 제공하고 확장 성공 비율과 미지원 요청 건수로 확인함

## Ⅶ. 결론

골든 패스는 조직 표준을 강제 문서가 아니라 가장 쉬운 기본 경로로 구현할 때 실효성이 생김.
