## Ⅰ. 개요
- **정의**: 소스코드를 실행하지 않고 정적 분석으로 보안 취약점을 탐지하는 기법
- **배경/필요성**: 개발 초기 단계에서 취약점을 발견할수록 수정 비용이 감소함
- **비유**: 건물 완공 전 설계도면에서 구조 결함을 찾는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DAST(283)와 비교 출제 빈출 | 소스코드 기반·빌드 전 탐지 | 오탐(False Positive) 한계 반드시 언급 |

> 요약: 코드 실행 없이 소스 수준에서 보안 결함을 조기 탐지하는 기법임

## Ⅱ. 구성요소
```text
Source Code --> Parser --> AST/CFG 생성 --> 규칙 엔진 매칭 --> 취약점 리포트
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 파서 | 소스코드를 AST·CFG로 변환하여 구조화 | 문장을 문법 트리로 분해 |
| 규칙 엔진 | CWE 기반 취약점 패턴과 코드 구조 비교 매칭 | 체크리스트 대조 검사 |
| 오염 분석 | 외부 입력이 위험 함수까지 전파되는 경로 추적 | 오염된 물이 수도관을 타고 흐르는 경로 추적 |
| 리포트 생성기 | 취약점 위치·심각도·수정 가이드 출력 | 진단서 발급 |

> 요약: 파서→규칙 매칭→오염 분석→리포트의 정적 분석 파이프라인임

## Ⅲ. 절차
```text
코드 체크인 --> SAST 스캔 --> 결과 분류 --> 수정/예외 처리
```
- 1단계: 형상관리 시스템에 코드 커밋 시 SAST 자동 트리거
- 2단계: AST·CFG 기반 패턴 매칭 및 오염 경로 분석 수행
- 3단계: 탐지 결과를 참양성·오탐으로 분류(Triage)
- 4단계: 참양성은 코드 수정, 오탐은 예외 등록 후 재스캔

> 요약: 커밋→스캔→분류→수정의 자동화 루프로 보안 결함을 조기 제거함

## Ⅳ. 문제점
- 높은 오탐률: 실행 컨텍스트 부재로 실제 도달 불가 경로도 경고 — 개발자 피로 유발
- 런타임 취약점 미탐지: 인증·권한 등 실행 시 발현 결함 탐지 불가 — DAST 보완 필요
- 언어·프레임워크 종속: 분석 규칙이 특정 언어에 한정 — 다중 기술스택 환경에서 도구 분산

> 요약: 오탐 과다·런타임 미탐·언어 종속이 주요 한계임

## Ⅴ. 개선방안
1. 단기: 오탐 이력 학습 기반 우선순위 자동 조정으로 분류 효율 향상
2. 중기: DAST·SCA(284)와 결합한 복합 보안 테스트 체계 구축
3. 장기: AI 기반 의미 분석 도입으로 언어 비종속 범용 분석 엔진 확보

> 요약: 오탐 최적화·복합 테스트·AI 분석으로 정적 분석 실효성 강화 필요

## Ⅵ. 전망
- 발전 방향: IDE 내장형 실시간 SAST로 Shift-Left 보안 가속
- 기술사적 판단: DevSecOps 파이프라인의 기본 게이트로 정착 중임
- 기술사 제언: SAST·DAST·SCA 통합 대시보드 기반 취약점 수명주기 관리 체계 수립 필요
