## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 물리 H/W 자원을 논리적으로 분리하거나 타 아키텍처를 모방하여 실행하는 기술 |
| 배경 | 자원 활용 극대화, 레거시 시스템 유지, 이종 플랫폼 간 S/W 이식성 확보 |
| 출제 의도 | 전가상화 vs 반가상화, 컨테이너화, 에뮬레이션(QEMU 등) 차이 이해 |

## Ⅱ. 구성요소
```text
[ Full-Virt ]      [ Para-Virt ]      [ Emulation ]
+-----------+      +-----------+      +-----------+
| Guest OS  |      | Guest OS* |      | Guest OS  |  (x86)
+-----------+      +-----------+      +-----------+
| Binary Mod|      | Hypercall |      | ISA Trans |
+-----------+      +-----------+      +-----------+
| Hypervisor|      | Hypervisor|      | Emulator  |  (ARM Host)
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 전가상화 | 게스트 OS 수정 없이 그대로 실행 | 완벽한 위장 |
| 반가상화 | 성능을 위해 OS 일부를 수정(Hypercall) | 협조적인 위장 |
| 에뮬레이션 | 명령어 집합(ISA) 자체를 소프트웨어로 번역 | 실시간 통역기 |
> 요약: 가상화는 자원 공유가 목적, 에뮬레이션은 호환성 제공이 주 목적임.

## Ⅲ. 절차
```text
Inst Exec -> Trap/Interception -> Handler Code -> Hardware Emulation
      ^                                                |
      +------ (Return Result) <------ Update State <---+
```
1. 명령 가로채기: 게스트 OS가 특권 명령 실행 시 가상화 계층이 이를 감지 및 가로챔.
2. 바이너리 변환: 비가상화 지원 명령을 가상화 가능 코드로 실시간 변환(Binary Trans).
3. 하드웨어 시뮬레이션: 실제 물리 자원 대신 가상 장치의 상태를 변경하고 결과 생성.
4. 결과 반환: 작업이 완료된 것처럼 게스트 OS에 알리고 다음 명령 수행.
> 요약: 하드웨어 보조 가상화(Intel VT-x)를 통해 처리 속도를 획기적으로 개선함.

## Ⅳ. 문제점
- 전가상화 시 발생하는 잦은 트랩 및 에뮬레이션의 CPU 번역 오버헤드로 성능 저하.
- 하드웨어 직접 접근(Passthrough) 불가 시 고성능 I/O(GPU 등) 활용 한계.

## Ⅴ. 개선방안
- 하드웨어 가속 가상화 기술 적극 활용 및 Virtio 등 표준화된 I/O 인터페이스 적용.
- 가볍고 빠른 컨테이너 가상화와 강력한 격리의 VM 가상화 장점을 결합한 Katacontainer.

## Ⅵ. 전망
- Confidential Computing: 메모리 내 데이터까지 암호화하여 가상화 보안의 정점 달성.
- WebAssembly (Wasm): OS 독립적인 샌드박스 실행 환경으로 서버사이드 가상화 패러다임 변화.
