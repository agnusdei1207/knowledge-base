## Ⅰ. 개요
- 정의: 클라우드의 이점(탄력성, 확장성)을 활용하기 위해 설계, 빌드, 운영되는 애플리케이션.
- 출제 의도: 단순 이관(Lift & Shift)이 아닌 클라우드 최적화 핵심 4대 요소 및 철학 이해도 확인.

## Ⅱ. 구성요소
- ASCII 구조도
  < Cloud Native 4 Pillars >
  [ MSA ] ---------- [ DevOps ]
     |                  |
  [ Container ] ---- [ CI/CD ]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| MSA | 앱을 작고 독립적인 서비스 단위로 분해한 구조 | 레고 블록 |
| Container | 환경 독립성과 표준화된 배포 단위 제공 | 표준 규격 컨테이너 |
| DevOps & CI/CD | 개발-운영 통합 및 배포 자동화 체계 | 자동화된 공정 라인 |
> 요약: 민첩성(Agility)과 복원력(Resilience)을 위해 기술과 문화를 결합한 형태임.

## Ⅲ. 절차
- ASCII 흐름도
  [Design for Cloud] -> [Microservice Build] -> [Automated Test] -> [Iterative Release]
- 4단계 설명
1. 상태 비저장(Stateless) 및 느슨한 결합(Loose Coupling) 원칙으로 설계함.
2. 컨테이너 기반으로 서비스를 패키징하여 환경 일관성 확보함.
3. CI/CD 파이프라인을 통해 코드 변경사항을 지속 검증 및 반영함.
4. 사용자 피드백을 기반으로 작고 빈번한 업데이트를 수행함.
> 요약: 지속적인 변화에 대응 가능한 유연한 소프트웨어 생명주기 구현함.

## Ⅳ. 문제점
- 분산 복잡성: 수많은 서비스 간 통신 관리 및 데이터 일관성 유지의 난이도 급증함.
- 가시성 저하: 장애 발생 시 여러 서비스를 거치는 요청의 흐름 추적이 어려움.

## Ⅴ. 개선방안
- Observability 강화: 분산 트레이싱, 메트릭, 로깅 통합 도구 도입하여 실시간 가시성 확보함.
- 인프라 자동화: IaC(Terraform 등)를 통해 인프라 구성을 코드화하여 가변 인프라 방지함.

## Ⅵ. 전망
- 플랫폼 엔지니어링(Platform Engineering)으로 진화하여 개발자의 인프라 부담 최소화 추세임.
- AI/ML 기술이 결합된 AIOps를 통해 장애 감지 및 자가 치유(Self-healing) 고도화될 것임.
- 지속 가능성(Sustainability)이 주요 지표로 부상하며 에너지 효율적인 클라우드 설계 중시됨.
