# 📖 【암기용】 개념 완전 이해

> 목적: A/B 테스트 모델 평가를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: A/B 테스트 모델 평가는 **온라인 통제 실험(Online Controlled Experiment)**의 하나로, 사용자를 무작위로 두 집단(A/B)에 배정해 기존 모델과 신규 모델의 실제 업무 KPI 차이를 **통계적 가설 검정**으로 판별하는 방법이다.
- **왜 필요한가**: 오프라인 정확도(AUC 등)가 올라도 실제 클릭·구매·이탈 같은 사용자 행동은 달라지지 않을 수 있다. 모델 지표와 비즈니스 지표가 항상 같이 움직이는 게 아니므로, 실 사용자 반응으로 직접 확인해야 한다.
- **핵심 직관**: 두 약을 무작위로 나눈 환자 집단에 각각 투여하고, 회복률 차이가 우연인지 진짜 효과인지 통계로 검정하는 임상시험과 같다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 온라인 통제 실험(Online Controlled Experiment) | 실 사용자 트래픽을 무작위로 나눠 변경 전후 효과를 비교하는 실험 방법론 — A/B 테스트는 그 대표 형태 | 임상시험의 무작위 대조군 실험(RCT) |
| 통계적 가설 검정 | 관측된 차이가 우연(표본 변동)인지, 실제 효과인지를 확률적으로 판정하는 절차 | 동전이 진짜 조작됐는지 여러 번 던져 확인하는 것 |
| 귀무가설(H0) / 대립가설(H1) | H0: "두 모델의 KPI는 차이가 없다", H1: "차이가 있다" — 검정은 H0를 기각할 수 있는지를 본다 | "무죄 추정" — 유죄 증거가 충분해야 뒤집는다 |
| 유의수준(α) | H0가 참인데도 잘못 기각할 확률의 허용치 — 보통 0.05(5%) | 억울하게 유죄 판정할 확률을 5%로 제한 |
| 검정력(Power, 1-β) | 실제로 차이가 있을 때 그것을 통계적으로 감지해낼 확률 — 보통 80% 목표 | 진짜 범인을 놓치지 않을 확률 |
| p-value | H0가 참이라고 가정했을 때, 지금 관측한 차이(또는 더 극단적 차이)가 우연히 나올 확률 | p-value 0.03이면 "우연이면 3%만 이런 결과가 나온다" |
| 최소 검출 효과(MDE) | 실무적으로 의미 있다고 보는 최소 차이 크기 — 이보다 작은 차이는 검정 설계에서 무시 | 다이어트 효과가 0.1kg면 무의미, 3kg는 의미 있다고 미리 정하는 것 |
| SRM(Sample Ratio Mismatch) 검정 | 의도한 배정 비율(예 50:50)과 실제 배정 비율이 통계적으로 어긋나는지 확인하는 사전 점검 | 동전을 1만 번 던졌는데 앞면이 6천 번 나오면 동전을 의심 |
| Guardrail KPI / Kill Switch | 실험 중 절대 악화되면 안 되는 지표(오류율·지연)와, 그 지표가 기준을 넘으면 실험을 즉시 멈추는 장치 | 항공기 자동조종의 비상 정지 버튼 |

## 깊이 이해

### 배경 — 모델 지표와 비즈니스 지표는 다른 것을 잰다
추천 모델의 AUC가 0.85에서 0.88로 올라도 실제 매출은 그대로일 수 있다. AUC는 "순위를 얼마나 잘 매기는가"를 재고, 매출은 사용자가 실제로 클릭하고 결제까지 이어지는가를 잰다. 이 둘 사이의 간극을 메우려면 오프라인 지표가 아니라 실 사용자 행동으로 직접 검증해야 하고, 그 표준 방법이 A/B 테스트다.

### 표본 수는 왜, 어떻게 정하는가 — 수치로 계산해 보기
표본 수를 무작정 늘리거나 줄이면 안 된다. 너무 적으면 진짜 효과가 있어도 통계적으로 못 잡아내고(검정력 부족), 너무 많으면 실험 기간·비용이 커진다. 두 비율 비교(전환율 A vs B)의 근사식은 다음과 같다.

n ≈ 16 × p(1-p) / Δ²  (α=0.05, power=80% 기준 경험적 근사)

예: 현재 전환율(baseline) p=3%(0.03), 실무적으로 의미 있다고 본 최소 차이(MDE) Δ=0.5%p(0.005)라 하면,
p(1-p) = 0.03 × 0.97 = 0.0291
n ≈ 16 × 0.0291 / 0.005² = 0.4656 / 0.000025 ≈ 18,624

즉 그룹당 약 1만 8,600명, 양 그룹 합쳐 약 3만 7,000명의 표본이 있어야 0.5%p 차이를 유의하게 검출할 수 있다. 트래픽이 하루 3,000명이면 최소 약 12~13일은 실험을 돌려야 한다는 뜻이 되고, 이것이 "실험 기간 14일" 같은 설계값의 근거다.

### p-value·유의수준을 실제로 어떻게 읽는가
실험 결과 A군 CTR 3.0%, B군 CTR 3.15%, p-value=0.03이 나왔다고 하자. 유의수준 α=0.05로 미리 정했다면, p-value(0.03) < α(0.05)이므로 "이 차이가 우연히 나왔을 확률은 5%보다 작다"는 뜻이 되어 H0(차이 없음)를 기각하고 B(신규 모델)를 채택한다. 반대로 p-value=0.12가 나오면 α=0.05 기준을 통과하지 못해 "차이가 있다고 말할 근거가 부족하다"로 결론 내린다 — 이는 "차이가 없다"의 증명이 아니라 "증거 부족"이라는 점이 자주 오해된다.

### SRM 검정 — 배정 자체가 깨졌는지 먼저 확인한다
결과를 해석하기 전에 반드시 배정 비율부터 점검해야 한다. 의도는 50:50인데 실제로 A군 52,000명, B군 48,000명이 모였다면, 카이제곱 검정으로 이 차이가 우연 범위인지 확인한다(SRM 검정). 우연 범위를 벗어나면 배정 로직(예: user id hash 편향, 특정 디바이스에서 B군 리다이렉트 실패)에 버그가 있다는 신호이며, 이 상태에서 나온 KPI 차이는 신뢰할 수 없다.

### 판별 원리 — A/B가 필요한 상황
섀도 배포는 시스템이 안 죽는지만 보여주고, 카나리는 제한된 실노출로 안전성만 재확인한다. 반면 "신규 모델이 사용자 행동(클릭·구매·이탈)을 실제로 개선하는가"를 확정해야 하는 경우, 즉 효과의 통계적 증명이 필요한 경우에만 A/B 테스트를 쓴다. 추천·검색·광고처럼 결과가 사람의 선택에 영향을 주는 모델이 전형적 대상이다.

### 비유와 흔한 오해
- **비유**: 매장 진열 방식을 두 가지로 나눠 고객 반응을 비교하되, 요일과 매장 위치가 한쪽에 치우치지 않도록 무작위로 나누는 것과 같다.
- **오해 1**: "50:50으로만 나누면 A/B 테스트다" — 틀렸다. 표본 수 산정, 무작위 배정, 실험 기간, 중단 기준이 없으면 결과가 왜곡된다.
- **오해 2(피킹 문제)**: 실험 도중 결과를 수시로 들여다보다 유의해 보이는 순간 바로 중단하면(peeking) false positive가 크게 늘어난다. 사전에 정한 표본 수·기간까지 기다리거나, 도중 확인이 필요하면 sequential testing 같은 별도 통계 기법을 명시적으로 써야 한다.

## 연결 개념
- 카나리 배포: A/B 이전 단계에서 위험 축소 중심으로 일부 노출하는 점진적 배포
- 실험 설계: 가설, 표본 수(power analysis), 유의수준 설정이 A/B의 통계적 기반
- 온라인 평가: CTR·CVR·매출·이탈률 등 A/B가 실제로 측정하는 비즈니스 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: A/B 테스트 답안은 모델 정확도보다 가설, 무작위 배정, 표본 수, 통계 검정, 윤리·리스크를 중심으로 작성해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: A/B 테스트 모델 평가는 기존 모델과 신규 모델을 사용자 집단에 나눠 실제 KPI 차이를 통계적으로 검증하는 온라인 평가다.
> 2. **가치**: 오프라인 metric과 실제 업무 성과 간 차이를 확인해 모델 채택 여부를 데이터 기반으로 결정한다.
> 3. **판단 포인트**: 무작위 배정, 표본 수, 유의수준, 실험 기간, 중단 기준이 없으면 결과 해석이 왜곡된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 온라인 모델 평가 이해 | A군/B군, KPI, 통계 검정 | 단순 트래픽 분할로 설명 |

> 요약: A/B 테스트는 신규 모델 효과를 실제 사용자 행동과 통계적 근거로 판정하는 방법이다.

## Ⅰ. 개요 및 필요성

- 개요: A/B 테스트는 온라인 모델 효과 검증 실험이다.
- 배경: 오프라인 평가가 높은 모델도 실제 사용자 행동 KPI와 다를 수 있다.
- 필요성: 무작위 집단 비교와 통계 검정으로 신규 모델 채택 여부를 판단해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
User -> Random Assignment -> Group A Baseline
                         / Group B Candidate -> KPI Log -> Statistical Test -> Decision
```

| 구성요소 | 역할 | 통제 기준 |
|:---|:---|:---|
| 가설·KPI | 실험 목표와 성공 기준 정의 | CTR, CVR, 매출, 이탈률 |
| 무작위 배정 | 사용자 편향을 줄이는 집단 분리 | user id hash |
| 실험 로그 | 노출, 클릭, 전환, 지연 수집 | event schema |
| 통계 검정 | 차이의 우연 가능성 판단 | p-value, confidence interval |

> 요약: A/B 테스트는 집단 배정부터 KPI 로그와 통계 판정까지 하나의 실험 설계로 운영된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
가설 수립 -> 표본 수 산정 -> 무작위 배정 -> 모델 노출 -> KPI 수집 -> 통계 검정 -> 채택/중단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 성공 KPI와 최소 효과 크기 정의 | CTR 1%p 증가 목표 |
| 2 | 표본 수와 실험 기간 산정 | power 80%, alpha 0.05 |
| 3 | 사용자 무작위 배정과 노출 | 세그먼트 균형 |
| 4 | 통계 검정과 의사결정 | p-value 0.05, CI 확인 |

> 요약: A/B 테스트는 사전 가설과 표본 수를 정하고 실험 후 통계 검정으로 모델 채택을 판단한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | A/B 테스트 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 오프라인 홀드아웃 | 온라인 무작위 실험 | 사용자 행동 KPI 필요 |
| 비용/성능 | 실험 운영 없음 | 로그, 분석, 기간 비용 | 표본 수 확보 가능 |
| 운영/위험 | 노출 전 판단 | 제한된 사용자 영향 | 중단 기준과 윤리 검토 |

> 요약: 모델 채택이 사용자 행동과 매출에 좌우되면 A/B 테스트를 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 표본 편향 | 무작위 배정 실패 | user id hash, segment check | SRM 검정 |
| 조기 중단 오류 | 중간 결과만 보고 결정 | 사전 기간 고정, sequential test | false positive rate |
| 사용자 피해 | 후보 모델 오류 | guardrail KPI, kill switch | complaint rate |

> 요약: A/B 리스크는 표본 편향, 조기 중단, 사용자 피해이며 실험 설계와 중단 장치로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 통계 신뢰 | alpha 0.05, power 80% | 표본 수 계산 |
| 업무 KPI | CTR 1%p 증가 또는 CVR 개선 | 이벤트 로그 분석 |
| 서비스 품질 | p95 150ms, 오류율 0.1% 이하 | APM, gateway log |

> 요약: A/B 테스트 결과는 통계 신뢰, 업무 KPI, 서비스 품질이 모두 기준을 충족할 때 채택한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 실험 전 KPI, 최소 효과 크기, alpha 0.05, power 80%, 실험 기간 14일을 문서화함
2. user id hash로 A/B 집단을 고정하고 SRM 검정으로 배정 비율 이상 여부를 확인함
3. CTR, CVR, p95 지연, 오류율, 민원율을 대시보드화하고 guardrail 위반 시 kill switch를 실행함

**결론 (2줄):**
- 기술사 판단: 사용자 행동 KPI 검증이 필요한 추천·검색·광고 모델은 A/B 테스트를 적용하고, 안전 리스크가 큰 모델은 섀도와 카나리 후 진행함
- 향후 방향: A/B 테스트는 bandit, causal inference, feature flag 플랫폼과 결합해 온라인 실험 운영 체계로 발전함
