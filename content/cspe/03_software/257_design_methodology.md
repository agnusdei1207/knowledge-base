## Ⅰ. 개요
- 정의: 소프트웨어 구축 시 복잡도를 관리하고 품질을 확보하기 위한 설계 체계임
- 배경: 소프트웨어 규모 증대에 따른 유지보수 효율성 및 재사용성 요구 증가
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 구조적 방법론 | 모듈화, 하향식 설계 | 보통 |
| 객체지향 | 캡슐화, 상속, 다형성 | 매우높음 |

## Ⅱ. 구성요소 비교
- ASCII 구조도
  [ 구조적 ] : (기능/데이터 분리) [ Data ] <--- (Process)
  [ 객체지향 ] : (기능+데이터 통합) [ Object { Data + Method } ]

- 구성요소 표
| 구분 | 구조적 방법론 | 객체지향 방법론 |
|------|---------------|-----------------|
| 관점 | 프로세스, 기능 중심 | 객체, 데이터 중심 |
| 설계 방식 | 하향식 (Top-down) | 상향식 (Bottom-up) |
| 핵심 원리 | 분할과 정복 (Modularization) | 추상화, 캡슐화, 재사용 |

> 요약: 절차 중심에서 데이터와 행위를 묶은 자율적 객체 중심으로 진화함

## Ⅲ. 절차
- 4단계 설명
1. 요구분석: 사용자의 요구사항을 식별하고 기능적/비기능적 명세 작성함
2. 아키텍처설계: 시스템의 전체 구조를 결정하고 모듈/객체 간 관계 정의함
3. 상세설계: 각 모듈 내부의 로직(알고리즘)이나 객체의 속성과 메서드 설계함
4. 구현 및 검증: 설계도에 따라 코딩하고 설계 의도대로 동작하는지 테스트함

> 요약: 분석에서 설계로 이어지는 논리적 체계성을 통해 품질을 보장함

## Ⅳ. 문제점
- 구조적 방법론은 요구사항 변경 시 영향도가 전체로 확산되는 경직성 있음
- 객체지향 방법론은 지나친 추상화로 인해 학습 곡선이 높고 성능 저하 우려됨

## Ⅴ. 개선방안
- (단기) 응집도는 높이고 결합도는 낮추는 설계를 통해 모듈의 독립성 강화함
- (중기) 디자인 패턴을 적극 활용하여 검증된 설계 구조를 반복 적용함
- (장기) 도메인 주도 설계(DDD)를 도입하여 비즈니스 복잡도를 효과적으로 분해함

## Ⅵ. 전망
- 요구사항의 빠른 변화에 대응하는 애자일 설계 및 모델 주도 개발(MDD) 확산됨
- AI가 최적의 클래스 다이어그램이나 모듈 구조를 추천하는 지능형 설계 시대 도래함
