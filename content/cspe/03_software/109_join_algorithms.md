## 미리 알고가기

- NLJ는 바깥쪽 집합을 하나씩 읽으며 안쪽 집합을 찾아가는 중첩 반복 조인임
- Hash Join은 조인 키로 해시 테이블을 만든 뒤 같은 키를 빠르게 매칭하는 방식임
- Merge Join은 두 입력이 정렬돼 있을 때 순서대로 비교하며 결합하는 방식임

## Ⅰ. 개요

- **정의/개념**: 조인 알고리즘은 두 개 이상의 테이블을 조인 조건으로 결합할 때 어떤 자료 접근 방식과 메모리 구조와 정렬 전략을 사용할지 정하는 실행 기법으로, 대표적으로 NLJ와 Hash Join과 Merge Join이 활용됨.
- **배경/필요성**: 조인은 복합 질의의 비용 대부분을 차지하는 경우가 많으므로, 데이터 크기와 인덱스와 메모리 상태에 맞는 알고리즘을 고르지 못하면 같은 SQL도 성능 차이가 매우 커짐.

## Ⅱ. 특징

- NLJ는 바깥쪽 행마다 안쪽을 탐색하므로 바깥 결과가 작고 안쪽 인덱스가 있을 때 탐색량이 감소함
- Hash Join은 작은 입력으로 해시 테이블을 만들고 큰 입력을 probe하는 등치 조인에 사용함
- Merge Join은 정렬된 두 입력을 순차 비교하며 등치·범위 조건의 결과를 생성함
- 잘못 고른 조인 방식은 CPU와 메모리와 디스크 임시 작업 비용을 동시에 키움

## Ⅲ. 종류 및 비교

| 판단 기준 | NLJ | Hash Join | Merge Join |
|:---|:---|:---|:---|
| 잘 맞는 상황 | 바깥쪽 결과가 작고 인덱스 조회가 가능할 때 | 대용량 등치 조인일 때 | 입력이 이미 정렬됐거나 정렬 결과가 필요할 때 |
| 처리 경로 | 바깥 행별 안쪽 index·scan 반복 | build 입력 해시 생성 후 probe 입력 탐색 | 정렬된 양쪽 입력을 포인터로 순차 비교 |
| 한계 | 대용량 조인에서는 반복 탐색 비용이 큼 | 메모리가 부족하면 디스크 임시 작업이 늘어남 | 선행 정렬 비용이 크면 이점이 줄어듦 |
| 주요 자원 | 인덱스 접근과 임의 접근 입출력 | 해시 메모리 | 정렬 버퍼와 순차 입출력 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 바깥쪽과 안쪽 입력 | 어떤 집합을 먼저 읽고 어떤 집합을 찾아갈지 정해 비용 차이를 만듦 |
| 조인 조건 | 등치 조건인지 범위 조건인지에 따라 적합한 알고리즘이 달라짐 |
| 작업 메모리 | 해시 테이블과 정렬 버퍼가 메모리에 들어가는지 여부가 성능을 좌우함 |
| 임시 작업 경로 | 메모리가 부족할 때 디스크 임시 작업이나 추가 인덱스 조회가 발생함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 특성 분석  | --> | 알고리즘 선택   | --> | 조인 수행      | --> | 자원 사용 검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 특성 분석**: 데이터 크기와 정렬 상태와 인덱스 존재 여부를 확인함
2. **알고리즘 선택**: 비용이 가장 낮은 조인 방식을 고름
3. **조인 수행**: 선택된 방식으로 레코드를 결합함
4. **자원 사용 검증**: 임시 작업과 CPU와 입출력 사용량을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 선택도가 높은 조건으로 소량 데이터를 찾은 뒤 결합하는 조회에서는 NLJ가 유리할 수 있지만 안쪽 인덱스가 없으면 급격히 느려지므로 실행 계획의 인덱스 사용 여부와 최악 응답 시간을 확인함.
2. 대용량 배치나 분석성 등치 조인에서는 Hash Join이 유리하지만 메모리가 부족하면 임시 디스크 작업이 커지므로 임시 작업 비율과 처리량을 함께 확인함.

## Ⅶ. 결론

조인 알고리즘 선택은 문법 문제가 아니라 입력 데이터 특성과 메모리 조건을 바탕으로 가장 싼 결합 경로를 고르는 실행 전략임.
