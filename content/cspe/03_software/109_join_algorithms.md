## 미리 알고가기

- NLJ는 바깥쪽 집합을 하나씩 읽으며 안쪽 집합을 찾아가는 중첩 반복 조인임
- Hash Join은 조인 키로 해시 테이블을 만든 뒤 같은 키를 매칭하는 방식임
- Merge Join은 두 입력이 정렬돼 있을 때 순서대로 비교하며 결합하는 방식임
- 옵티마이저는 입력 크기·조인 조건·인덱스·메모리 추정값으로 조인 알고리즘을 선택함

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 조인 알고리즘은 입력 크기·조인 조건·인덱스·메모리를 핵심 축으로 설명함
- 비교표는 NLJ·Hash Join·Merge Join의 적합 조건·처리 방식·주요 한계를 대비함
- 조회·분석 DB는 p95 조인 지연·임시 파일 용량으로 검증함

## Ⅰ. 개요

- **정의/개념**: 조인 알고리즘은 조인 조건에 맞는 행을 결합하기 위해 반복 탐색·해시·정렬 병합 중 처리 방식을 선택하는 실행 기법임
- **배경/필요성**: 입력 크기·인덱스·정렬 상태·작업 메모리에 따른 조인 비용을 줄이기 위해 실행 조건에 맞는 알고리즘을 선택해야 함

### 쉽게 이해하기 (학습용)
- 두 명단에서 같은 사람을 찾을 때 한 명씩 찾기, 해시 사전 만들기, 정렬 명단 나란히 읽기를 선택하는 것임

## Ⅱ. 특징

- NLJ는 바깥쪽 행마다 안쪽을 탐색하므로 바깥 결과가 작고 안쪽 인덱스가 있을 때 탐색량이 감소함
- Hash Join은 작은 입력으로 해시 테이블을 만들고 큰 입력을 probe하는 등치 조인에 사용함
- Merge Join은 정렬된 두 입력을 순차 비교하며 등치·범위 조건의 결과를 생성함
- 잘못 고른 조인 방식은 CPU와 메모리와 디스크 임시 작업 비용을 동시에 키움

### 쉽게 이해하기 (학습용)
- 명단 크기와 정렬 상태와 작업 공간에 따라 가장 적은 수고가 드는 방법이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | NLJ | Hash Join | Merge Join |
|:---|:---|:---|:---|
| 적합 조건 | 바깥쪽 결과가 작고 안쪽 인덱스가 있을 때 | 대용량 등치 조인 | 입력이 정렬됐거나 정렬 결과가 필요할 때 |
| 처리 방식 | 바깥 행마다 안쪽 행을 반복 탐색 | 작은 입력으로 해시를 만들고 큰 입력을 탐색 | 정렬된 두 입력을 순차 비교 |
| 주요 한계 | 바깥 결과가 크면 반복 탐색 비용이 증가함 | 메모리가 부족하면 디스크 분할이 발생함 | 선행 정렬 비용이 크면 이점이 감소함 |

> 요약: NLJ는 소량 입력과 인덱스, Hash Join은 대용량 등치 조건, Merge Join은 정렬된 입력에 적합함.

### 쉽게 이해하기 (학습용)
- 작은 명단은 반복 탐색, 큰 등치 명단은 해시, 이미 정렬된 명단은 병합이 유리함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 바깥쪽과 안쪽 입력 | 어떤 집합을 먼저 읽고 어떤 집합을 찾아갈지 정해 비용 차이를 만듦 |
| 조인 조건 | 등치 조건인지 범위 조건인지에 따라 적합한 알고리즘이 달라짐 |
| 작업 메모리 | 해시 테이블과 정렬 버퍼가 메모리에 들어가는지 여부가 성능을 좌우함 |
| 임시 작업 경로 | 메모리가 부족할 때 디스크 임시 작업이나 추가 인덱스 조회가 발생함 |

> 요약: 입력 순서와 조인 조건이 처리 방식을 결정하고 작업 메모리와 임시 경로가 실제 조인 비용을 좌우함.

### 쉽게 이해하기 (학습용)
- 먼저 읽을 명단, 같은 사람을 판단할 열, 사용할 작업 공간을 함께 정함

## Ⅴ. 원리 및 절차 흐름도

```text
[입력 크기 추정] -> [조인 조건 판별] -> [인덱스·정렬·메모리 확인]
        -> [알고리즘 선택] -> [실제 행 수·임시 I/O 검증]
```

1. 필터 적용 뒤 바깥쪽·안쪽 입력의 실제 크기를 추정함
2. 등치·범위 조건과 인덱스·정렬 상태를 확인함
3. 소량 인덱스 탐색은 NLJ, 대용량 등치는 Hash Join, 정렬 입력은 Merge Join을 후보로 평가함
4. 실제 행 수, 반복 탐색, 메모리 초과와 임시 파일을 비교해 선택을 검증함

> 요약: 입력 규모와 조건·자원에 맞는 조인 방식을 고르고 실측 비용으로 다시 확인함.

### 쉽게 이해하기 (학습용)
- 명단 상태를 보고 찾는 방법을 고른 뒤 실제 횟수와 작업 공간이 예상과 맞는지 확인함

## Ⅵ. 실무 사례

1. 주문 상세 조회는 소량 결과와 안쪽 인덱스에 NLJ를 적용하고 p95 조인 지연·반복 탐색 수를 확인함
2. 집계 배치는 대용량 등치 조건에 Hash Join을 적용하고 처리량·임시 파일 용량을 확인함

### 쉽게 이해하기 (학습용)
- 소량 주문 상세는 반복 탐색으로, 대량 집계는 해시 결합으로 처리함
