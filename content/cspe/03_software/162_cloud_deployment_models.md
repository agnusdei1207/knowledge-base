## 미리 알고가기

- 퍼블릭 클라우드는 공급자 소유 자원을 여러 소비자에게 서비스 형태로 제공함
- 프라이빗 클라우드는 한 조직만 사용하는 클라우드 자원과 관리 체계를 구성함
- 하이브리드 클라우드는 프라이빗 환경과 퍼블릭 클라우드를 연결해 업무를 배치함
- 멀티 클라우드는 퍼블릭·프라이빗·하이브리드 같은 소유 형태가 아니라 둘 이상의 퍼블릭 공급자를 업무별로 병행하는 운영 구성임
- 워크로드 배치는 데이터 위치·규제·지연·서비스 종속성을 기준으로 실행 환경을 정하는 활동임

## 작성 근거(검토용)

- 배포 모델은 자원 소유보다 접근 범위·업무 배치·환경 간 결합 방식이 선택을 가르므로 이를 핵심으로 둠
- 네 모델을 자원·접근, 업무 배치, 운영 의존성의 같은 분석 수준에서 비교하고 연결·통제 구조는 Ⅳ 구성요소에서 다룸
- 모델별 배치 조건과 공통 관리 계층이 핵심이고 순차 처리 원리가 없으므로 별도 Ⅴ절을 두지 않음
- 제목부터 결론까지 5회 전수 검수하여 모델 범위와 표의 행·열 대응을 확인함

## Ⅰ. 개요

- **정의/개념**: 클라우드 배포 모델은 클라우드 자원의 소유·접근 범위와 워크로드가 실행되는 환경 조합을 구분하는 체계임
- **배경/필요성**: 데이터 규제·기존 시스템 연계·공급자 종속성을 반영하기 위해 워크로드 배치 기준이 필요함

## Ⅱ. 특징

- 자원 접근 주체와 운영 경계가 퍼블릭·프라이빗 모델을 구분함
- 환경을 결합하면 네트워크·ID·데이터·관측 체계를 함께 설계해야 함
- 워크로드마다 규제·지연·비용·관리 서비스 요구에 따라 실행 환경을 선택함
- 환경 수가 늘수록 공급자 장애 분리 가능성과 정책·운영 도구의 중복이 함께 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 퍼블릭 | 프라이빗 | 하이브리드 | 멀티 클라우드 |
|:---|:---|:---|:---|:---|
| 자원·접근 | 공급자 자원을 여러 소비자가 사용 | 한 조직 전용 자원을 사용 | 전용 환경과 퍼블릭 자원을 결합 | 여러 퍼블릭 공급자 자원을 사용 |
| 업무 배치 | 공급자 리전에 배치 | 조직 전용 환경에 배치 | 업무·데이터를 두 환경에 분리 | 업무를 공급자별로 분리하거나 중복 배치 |
| 운영 의존성 | 단일 공급자 API·서비스에 의존 | 조직이 플랫폼 수명주기를 담당 | 연결·데이터 동기화 도구에 의존 | 공급자별 API 차이와 이식 비용 발생 |

> 요약: 배포 모델은 자원 소유·업무 배치 범위와 그에 따른 운영 의존성으로 구분함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 워크로드 분류 | 데이터 등급·지연·가용성·서비스 요구로 배치 후보를 정함 |
| 실행 환경 | 퍼블릭 계정·프라이빗 클러스터·기존 데이터센터를 제공함 |
| 연결 계층 | DNS·라우팅·암호화 경로로 환경 간 통신을 구성함 |
| 공통 ID·정책 | 계정 연동과 권한·구성 기준을 환경마다 적용함 |
| 데이터 이동 계층 | 복제·동기화·백업 경로와 데이터 위치를 관리함 |
| 통합 관측·비용 | 환경별 로그·지표·사용 비용을 공통 기준으로 수집함 |

```text
                 +-> 퍼블릭 클라우드 A
공통 ID·정책 --->+-> 프라이빗 환경
                 +-> 퍼블릭 클라우드 B
                       |
                 통합 관측·비용
```

> 요약: 여러 실행 환경을 연결하더라도 ID·정책·관측 기준은 공통 관리 계층에서 통제함.

## Ⅵ. 실무 사례

1. 개인정보 DB는 프라이빗 환경에 두고 API를 퍼블릭에 배치해 왕복 지연·전송량을 확인함
2. 분석 작업은 공급자별 관리 서비스를 업무별로 배치하고 월간 비용·공급자 간 데이터 이동량을 확인함

## Ⅶ. 결론

- 클라우드 배포 모델은 데이터 통제 범위·환경 간 연결 비용·공급자 종속성을 기준으로 선택해야 함
