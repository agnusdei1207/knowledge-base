# 📖 【암기용】 개념 완전 이해

## 한눈에
- **스레드 스케줄링**: 프로세스가 아닌 스레드 단위로 CPU를 할당하는 기법. 커널이 관리하느냐(Kernel-level), 라이브러리가 관리하느냐(User-level)에 따라 다름.
- **스레드 풀 (Thread Pool)**: 매번 스레드를 만들고 지우는 대신, 미리 만들어 놓은 스레드 뭉치(Pool)를 재사용하여 **생성 비용과 자원 폭증을 막는 전략**.
- **핵심 직관**: 콜센터 상담원. 손님이 올 때마다 상담원을 새로 채용(스레드 생성)하고 해고하는 대신, 고정된 인원(스레드 풀)을 두고 대기표(작업 큐)를 받아 순서대로 처리함.

## 깊이 이해
- **매핑 모델**:
    - **1:1**: 사용자 스레드 1개당 커널 스레드 1개. 병렬 처리가 좋지만 커널 리소스 소모가 큼 (Java, Linux).
    - **M:1**: 여러 사용자 스레드를 커널 스레드 1개가 담당. 빠르지만 한 스레드가 블로킹되면 다 멈춤.
    - **M:N**: 두 장점을 결합. 복잡하지만 효율적 (Go Goroutine).
- **스레드 풀의 가치**:
    - **성능**: 생성/소멸 오버헤드(수십 µs) 제거.
    - **제어**: 갑작스러운 요청 폭주에도 스레드 수를 제한하여 메모리 고갈 및 스레싱 방지.
- **Work Stealing**: 노는 스레드가 바쁜 스레드의 작업 큐에서 일을 뺏어와 도와주는 알고리즘. (Java ForkJoinPool)

## 연결 개념
- **Process vs Thread (001)**: 스레드가 왜 가벼운지 기초 이해.
- **Context Switching (002)**: 스레드 전환 오버헤드.
- **Virtual Thread (027)**: 스레드 풀의 관리 부하마저 줄이는 최신 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 스레드 스케줄링은 실행 제어권의 할당 모델(1:1, M:N)에 관한 것이며, 스레드 풀은 한정된 실행 자원의 **재사용 및 임계값 관리**에 관한 전략임.
> 2. **기술적 핵심**: 스레드 풀은 **작업 큐(Work Queue)**와 **워커 스레드(Worker Thread)**로 구성되며, 요청 폭주 시 시스템의 안정적인 처리량(Throughput)을 유지하는 방어선 역할을 함.
> 3. **판단 포인트**: CPU 바운드 작업은 코어 수에 맞게, I/O 바운드 작업은 대기 시간을 고려하여 더 많은 수의 스레드를 풀에 배치하는 최적화가 필요함.

## Ⅰ. 효율적 병행 처리를 위한 스레드 관리 전략 개요
- **스레드 스케줄링**: 사용자 영역과 커널 영역 간의 실행 흐름 매핑 및 CPU 할당 제어.
- **스레드 풀**: 성능 향상과 자원 고갈 방지를 위해 미리 생성된 스레드 집합을 재사용하는 관리 기법.

## Ⅱ. 스레드 스케줄링 모델: User vs Kernel

### 1. 매핑 모델 비교
| 구분 | User-level (M:1) | Kernel-level (1:1) | Hybrid (M:N) |
|:---:|:---|:---|:---|
| **관리 주체** | 사용자 라이브러리 | OS 커널 | 양측 협력 |
| **속도** | 빠름 (커널 개입 없음) | 느림 (시스템 콜 필요) | 중간 |
| **병렬성** | 낮음 (멀티코어 활용 불가) | 높음 (코어별 스레드 할당) | 매우 높음 |
| **특이사항** | 한 스레드 블로킹 시 전체 중단 | 자원 소모 큼 (현대 표준) | Go, Erlang 등 사용 |

### 2. 스케줄링 방식
- **PCS (Process-Contention Scope)**: 사용자 스레드들끼리 경쟁 (M:1, M:N 모델).
- **SCS (System-Contention Scope)**: 시스템 전체 스레드와 경쟁 (1:1 모델).

## Ⅲ. 스레드 풀(Thread Pool)의 아키텍처와 동작 원리

### 1. 스레드 풀 구조도 (ASCII Diagram)
```text
[Request] ──▶ [Work Queue] ──────────┐
               (Blocking Queue)       │ (Task 할당)
                                      ▼
        ┌────────── Thread Pool ────────────────┐
        │  Thread 1 | Thread 2 | Thread 3 ...   │ (Idle Threads)
        └───────────────────────────────────────┘
                                      │
[Result]  ◀── (Task 완료) ─────────────┘
```

### 2. 주요 동작 메커니즘
1. **Init**: 설정된 Core Size만큼 스레드 생성 및 대기.
2. **Submit**: 작업 인입 시 큐에 적재.
3. **Execution**: 유휴(Idle) 스레드가 큐에서 작업을 꺼내 처리.
4. **Scale**: 큐가 가득 차면 Maximum Size까지 스레드 추가 생성.
5. **Keep-alive**: 작업이 줄어들면 추가 생성된 스레드 회수.

## Ⅳ. 스레드 풀 설계 시 고려사항 (Tuning)

- **CPU Bound 작업**:
    - **적정 수**: `CPU 코어 수 + 1`.
    - **이유**: 컨텍스트 스위칭 오버헤드를 최소화하고 연산 효율 극대화.
- **I/O Bound 작업**:
    - **적정 수**: `CPU 코어 수 * (1 + 대기시간 / 서비스시간)`.
    - **이유**: I/O 대기 동안 다른 스레드가 CPU를 써야 하므로 더 많은 스레드 필요.
- **큐 정책**:
    - **Bounded Queue**: 메모리 고갈 방지를 위해 크기 제한 필수.
    - **Rejection Policy**: 큐가 꽉 찼을 때의 처리 (Abort, Caller-runs, Discard 등).

## Ⅴ. 스레드 풀의 장점 및 리스크

- **장점**:
    - **응답성**: 생성 지연 시간 제거.
    - **안정성**: 스레드 폭증(Thread Explosion) 방지.
    - **운영 효율**: 가용 자원 내에서 처리량(Throughput) 최대화.
- **리스크**:
    - **데드락**: 풀 내 스레드들이 서로의 작업 완료를 기다릴 때 발생 (Thread Starvation Deadlock).
    - **누수**: 종료되지 않은 스레드가 메모리를 점유.

## Ⅵ. 기술사 관점의 결론 및 제언
- 현대 고성능 서버 아키텍처는 **'적정 크기의 스레드 풀'**과 **'비동기 논블로킹 I/O'**의 조합이 기본임.
- **최신 경향**: 최근 Java 21의 **Virtual Thread** 도입으로, 기존의 무거운 커널 스레드 기반 풀링 방식에서 벗어나 "작업 하나당 스레드 하나"를 할당하면서도 리소스를 거의 쓰지 않는 방식으로 패러다임이 전환되고 있음.
