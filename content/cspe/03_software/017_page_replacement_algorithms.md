# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 가상 메모리 관리 중 페이지 폴트가 발생했을 때, 빈 프레임이 없다면 **어떤 페이지를 쫓아내고(Victim Page) 새 페이지를 들일지** 결정하는 방법.
- **핵심 직관**: 좁은 책상에서 공부하기. 책상이 꽉 찼는데 새 책을 보려면, 지금 있는 책 중 하나를 책꽂이로 돌려보내야 함. 어떤 책을 뺄 것인가? (제일 먼저 꺼낸 책? 제일 안 본 지 오래된 책?)
- **목표**: **페이지 폴트 횟수를 최소화**하여 시스템 성능(Throughput)을 높이는 것.

## 깊이 이해
- **Belady의 모순 (Belady's Anomaly)**: 프레임을 더 많이 줬는데(책상을 넓혀줬는데) 오히려 페이지 폴트가 더 많이 발생하는 기현상. (FIFO 알고리즘에서 발생)
- **주요 알고리즘**:
    - **FIFO (First-In, First-Out)**: 가장 먼저 들어온 놈을 쫓아냄. (간단하지만 비효율적)
    - **OPT (Optimal)**: 앞으로 가장 오랫동안 안 쓰일 놈을 쫓아냄. (이론상 최강, 현실은 미래를 몰라서 구현 불가)
    - **LRU (Least Recently Used)**: 가장 오랫동안 안 쓰인 놈을 쫓아냄. (과거는 미래의 거울, 가장 널리 쓰임)
    - **LFU (Least Frequently Used)**: 참조 횟수가 가장 적은 놈을 쫓아냄.
    - **NUR (Not Used Recently) / Clock**: 최근에 안 쓴 놈을 찾되, 하드웨어 비트(Reference Bit)를 써서 LRU를 흉내 내는 경량 방식.

## 연결 개념
- **Virtual Memory (015)**: 페이지 교체가 필요한 배경.
- **Locality (018)**: LRU가 잘 동작하는 이유 (최근에 쓴 놈을 또 쓸 확률이 높음).
- **Thrashing (015)**: 페이지 교체가 너무 빈번해서 시스템이 망가지는 현상.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 한정된 물리 메모리(Frame) 자원을 효율적으로 운영하기 위해, 향후 참조 가능성이 가장 낮은 페이지를 식별하여 교체하는 **자원 회수 전략**임.
> 2. **기술적 핵심**: 시간 지역성(Temporal Locality)에 기반한 **LRU**와 이를 하드웨어 비트로 최적화한 **Clock** 알고리즘이 현대 OS의 주류이며, 페이지 폴트 최소화가 목표임.
> 3. **판단**: 알고리즘 선택 시 구현의 복잡성(Overhead)과 페이지 폴트 감소율 사이의 트레이드오프를 고려해야 함.

## Ⅰ. 메모리 효율의 결정자, 페이지 교체 알고리즘의 개요
- **정의**: 페이지 부재 발생 시 물리 메모리의 빈 프레임을 확보하기 위해 교체 대상(Victim Page)을 선정하는 규칙.
- **목적**: 페이지 부재율(Page Fault Rate) 최소화, 시스템 처리량 향상.

## Ⅱ. 주요 페이지 교체 알고리즘 상세 분석

| 알고리즘 | 선정 기준 (Victim) | 특징 | 단점 |
|:---:|:---|:---|:---|
| **FIFO** | 가장 먼저 들어온 페이지 | 구현 용이, 공정성 | **Belady의 모순** 발생 가능 |
| **OPT** | 향후 가장 오랫동안 사용 안 될 페이지 | **이론상 최적(Lower Bound)** | 미래 예측 불가 (구현 불가) |
| **LRU** | 가장 오랫동안 사용되지 않은 페이지 | **지역성(Locality)** 활용, 우수한 성능 | 시간 기록/스택 유지 오버헤드 |
| **LFU** | 참조 횟수가 가장 적은 페이지 | 집중 참조 페이지 유지 | 초반에만 쓰이고 안 쓰이는 페이지 적체 |
| **NUR / Clock** | 참조/변조 비트가 0인 페이지 | LRU 근사, 하드웨어 비트 활용 | LRU보다 정교함은 떨어짐 |

## Ⅲ. FIFO의 치명적 결함: Belady의 모순 (Belady's Anomaly)

- **현상**: 프로세스에 할당된 프레임 수가 증가했음에도 불구하고 페이지 부재 횟수가 오히려 증가하는 현상.
- **원인**: FIFO는 페이지의 '참조 시점'이 아닌 '적재 시점'만 따지기 때문에, 자주 쓰이는 페이지를 적재 순서가 됐다는 이유로 쫓아내기 때문임. (LRU, OPT는 발생하지 않음)

## Ⅳ. 현대 OS의 실용적 선택: Clock 알고리즘 (Second Chance)

### 1. 동작 원리
1. 각 프레임에 **Reference Bit** (1: 참조됨, 0: 참조안됨) 부여.
2. 교체 시 포인터(시계바늘)가 순회하며 Bit 확인.
3. Bit가 1이면 0으로 바꾸고 기회를 한 번 더 줌 (**Second Chance**).
4. Bit가 0인 놈을 만나면 즉시 교체.

### 2. 가치
- LRU의 성능에 근접하면서도, 시간 기록(Timestamp)이나 리스트 재배치 오버헤드가 없어 커널에서 매우 효율적임.

## Ⅴ. 알고리즘 성능 평가 및 고려사항

- **평가 지표**: 페이지 부재 횟수 (Page Fault Count).
- **고려사항**:
    - **Dirty Bit (Modified Bit)**: 내용이 수정된 페이지는 디스크에 다시 써야 하므로(Write-back), 수정되지 않은 페이지를 우선 교체하는 것이 비용 면에서 유리함.
    - **Global vs Local Replacement**: 시스템 전체 프레임에서 뺏어올지, 자기 프로세스 프레임 내에서만 바꿀지 결정.

## Ⅵ. 기술사 관점의 결론 및 제언
- 페이지 교체 알고리즘은 **'과거의 데이터로 미래를 예측'**하는 통계적 최적화의 영역임.
- **실무 제언**: 고부하 시스템에서는 알고리즘 자체보다 **'페이지 폴트 발생을 원천 차단'**하는 것이 중요함. 따라서 애플리케이션 레벨에서 데이터 접근의 지역성을 극대화하도록 자료구조(예: B-Tree 최적화)를 설계하고, 중요한 데이터는 **mlock** 등을 통해 물리 메모리에 상주시켜야 함.
