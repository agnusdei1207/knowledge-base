## 미리 알고가기

- 전가상화는 게스트 OS 수정 없이 하이퍼바이저가 전체 하드웨어를 가상화하는 방식임
- 반가상화는 게스트 OS가 하이퍼바이저 존재를 인지하고 협력하는 방식임
- 컨테이너는 커널을 공유하면서 프로세스 격리를 제공하는 OS 수준 가상화임

## 작성 근거(검토용)

- 세 방식은 게스트 수정·격리 단위·커널·실행 경로·자원 비용·적용 환경으로 비교함
- 실행 환경 생성이라는 공통 생명주기 절차는 구조 차이를 설명하지 못해 삭제함
- 규제 서비스와 내부 플랫폼을 분리해 VM 격리·컨테이너 커널 공유를 직접 검증함

## Ⅰ. 개요

- **정의/개념**: 전가상화·반가상화·컨테이너는 실행 환경을 분리하는 방식으로, 전가상화는 가상 하드웨어를 제공하고 반가상화는 수정된 게스트가 하이퍼콜을 사용하며 컨테이너는 호스트 커널을 공유함
- **배경/필요성**: 서비스별 격리 수준·게스트 수정 가능성·배포 단위에 맞는 실행 환경을 정하기 위해 가상화 구조의 선택 기준이 필요함

## Ⅱ. 특징

- 전가상화는 수정하지 않은 게스트 OS를 독립 커널로 실행하며 장치 에뮬레이션과 VM exit 비용이 발생함
- 반가상화는 협력 인터페이스를 통해 I/O와 특권 연산 비용을 줄일 수 있음
- 컨테이너는 호스트 커널을 공유해 게스트 OS 부팅을 생략하며 namespace와 cgroup으로 실행 환경을 분리함
- 격리 경계·게스트 수정 가능성·배포 단위를 기준으로 세 방식을 선택함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전가상화 | 반가상화 | 컨테이너 |
|:---|:---|:---|:---|
| OS 수정 필요 | 없음 | 있음 또는 전용 드라이버 필요 | 없음 |
| 격리 단위 | VM 단위 | VM 단위 | 프로세스 단위 |
| 실행 경로 | 장치 에뮬레이션과 VM exit 경유 | hypercall·전용 드라이버 경유 | 호스트 커널 시스템 호출 사용 |
| 커널 구조 | 게스트별 독립 커널 | 게스트별 독립 커널 | 호스트 커널 공유 |
| 시작·자원 비용 | 게스트 OS 부팅·VM 메모리 | 게스트 OS 부팅·전용 드라이버 | 프로세스 시작·이미지 계층 |
| 대표 적용 사례 | 미수정 게스트·테넌트 격리 | 가상 I/O 성능 조정 | 애플리케이션 배포·확장 |

> 요약: 전가상화는 미수정 게스트, 반가상화는 협력 인터페이스, 컨테이너는 호스트 커널 공유로 실행 환경을 분리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 하이퍼바이저 계층 | 전가상화·반가상화 VM의 가상 하드웨어와 자원 접근을 중재함 |
| 게스트 OS·런타임 | VM은 독립 커널을, 컨테이너는 호스트 커널과 런타임을 사용함 |
| 가상 장치 인터페이스 | 에뮬레이션·하이퍼콜·반가상화 드라이버로 I/O를 전달함 |
| 격리 경계 | VM은 하이퍼바이저, 컨테이너는 네임스페이스·cgroup 경계를 사용함 |

> 요약: VM은 하이퍼바이저와 독립 커널로, 컨테이너는 네임스페이스·cgroup과 공유 커널로 격리함.

## Ⅵ. 실무 사례

1. 규제형 멀티테넌트 서비스는 VM별 자원 한도를 설정하고 격리 위반 수와 I/O 지연을 확인함
2. 내부 애플리케이션 플랫폼은 컨테이너 런타임 정책을 적용하고 시작시간과 호스트당 인스턴스 수를 확인함

## Ⅶ. 결론

- 전가상화·반가상화·컨테이너는 게스트 수정 가능성·격리 경계·커널 공유·배포 단위로 선택함
