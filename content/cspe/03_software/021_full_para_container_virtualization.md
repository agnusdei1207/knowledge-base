# 📖 【암기용】 개념 완전 이해

## 한눈에
- **전가상화 (Full Virtualization)**: 하드웨어를 완벽하게 흉내 냄. Guest OS는 자신이 가상 환경에 있는지 모르며, **수정 없이** 그대로 사용 가능. (느리지만 호환성 좋음)
- **반가상화 (Para Virtualization)**: 하드웨어를 흉내 내는 대신, Guest OS가 하이퍼바이저와 대화하도록 **OS 커널을 수정**함. (빠르지만 OS 수정 필요)
- **컨테이너 (Container)**: OS를 가상화하지 않고, **호스트 OS의 커널을 공유**하며 프로세스만 격리함. (극강의 가벼움, 클라우드 네이티브 표준)

## 깊이 이해
- **전가상화의 핵심: Binary Translation**: Guest OS가 날리는 특권 명령을 하이퍼바이저가 실시간으로 가로채서(Trap) 실행 가능한 명령으로 바꿈. 이 과정에서 오버헤드 발생.
- **반가상화의 핵심: Hypercall**: Guest OS가 특권 명령을 직접 내리는 대신, 하이퍼바이저에게 "이것 좀 해줘"라고 정중하게 요청(Hypercall)함. 
- **하드웨어 가지원 (HVM)**: Intel VT-x 등이 나오면서 전가상화도 하드웨어 도움으로 반가상화만큼 빨라짐.
- **컨테이너의 마법**: 리눅스 커널의 **cgroups**(자원 제한)와 **namespaces**(이름 공간 격리)를 사용하여, 별도의 OS 부팅 없이 격리된 환경을 만듦.

## 연결 개념
- **Hypervisor (020)**: 전/반가상화를 구현하는 소프트웨어 층.
- **Docker/Kubernetes (170/173)**: 컨테이너 가상화의 대표적 솔루션.
- **MicroVM (020 연계)**: 컨테이너처럼 가볍지만 하이퍼바이저처럼 강력하게 격리하는 최신 기술.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 하드웨어를 완벽히 모사하는 **전가상화**, 효율적 협업을 위해 커널을 수정하는 **반가상화**, 그리고 OS 커널을 공유하여 오버헤드를 극단적으로 줄인 **컨테이너**로 진화함.
> 2. **기술적 핵심**: 특권 명령 처리를 위한 **Binary Translation(전)**, **Hypercall(반)**, 그리고 커널 수준의 **격리(컨테이너)** 기술이 각각의 차별점임.
> 3. **판단**: 완벽한 격리와 이기종 OS 지원이 필요하면 VM(전/반)을, 고속 배포와 자원 효율성이 최우선이면 컨테이너를 선택함.

## Ⅰ. 가상화 기술의 스펙트럼, 전/반가상화 및 컨테이너 개요
- **가상화 기술**: 물리적 자원을 추상화하여 독립적인 다수의 실행 환경을 구축하는 기술.
- **진화 방향**: 하드웨어 에뮬레이션(전가상화) -> 커널 수준 협업(반가상화) -> OS 공유 기반 격리(컨테이너).

## Ⅱ. 가상화 유형별 상세 비교 분석

### 1. 기술적 구조 및 차이점 비교표
| 구분 | 전가상화 (Full-V) | 반가상화 (Para-V) | 컨테이너 (Container) |
|:---:|:---|:---|:---|
| **핵심 기술** | Binary Translation | **Hypercall** | **Namespace, cgroups** |
| **OS 커널** | Guest OS 커널 수정 불필요 | **Guest OS 커널 수정 필수** | **Host OS 커널 공유** |
| **오버헤드** | 가장 큼 (에뮬레이션 부하) | 중간 (하이퍼콜 통신) | **매우 작음 (Native 수준)** |
| **격리 수준** | 매우 높음 (HW 수준) | 높음 (HW 수준) | 중간 (OS 프로세스 수준) |
| **성능** | 상대적으로 낮음 | 우수함 | **최우수** |
| **대표 사례** | VMWare, VirtualBox | Xen, KVM | Docker, Podman |

### 2. 하드웨어 가상화 지원 (HVM: Hardware Virtual Machine)
- 최근 CPU(Intel-VT, AMD-V)는 하이퍼바이저 전용 모드를 제공하여, 전가상화 환경에서도 OS 수정 없이 반가상화에 준하는 성능을 낼 수 있게 함.

## Ⅲ. 컨테이너 가상화의 핵심 기제 (리눅스 커널 기술)

1. **Namespace**: 프로세스별로 시스템 자원(PID, Network, Mount 등)을 독립적으로 보이게 하는 성벽 역할.
2. **Control Groups (cgroups)**: 프로세스 그룹별로 자원(CPU, 메모리, I/O) 사용량을 제한하는 계량기 역할.
3. **Layered File System (UnionFS)**: 변경 사항만 계층적으로 저장하여 이미지 크기를 최소화하고 배포 속도 향상.

## Ⅳ. 가상화 기술 선택을 위한 의사결정 매트릭스

| 요구사항 | 최적의 선택 | 이유 |
|:---:|:---:|:---|
| **이기종 OS 구동** | 전가상화 (Full-V) | Linux 호스트 위에서 Windows 구동 등 가능 |
| **Native 수준 성능** | 컨테이너 (Container) | 하이퍼바이저 계층의 중재가 없음 |
| **강력한 보안/격리** | 하이퍼바이저 (Type 1) | 커널 취약점에 의한 전파 차단 가능 |
| **클라우드 확장성** | 컨테이너 (K8s) | 이미지 기반의 빠른 복제와 배포 용이 |

## Ⅴ. 기술적 심화: 하이브리드 모델의 등장

- **가상화의 융합**: 컨테이너의 가벼움을 유지하면서 하이퍼바이저의 격리성을 제공하는 **MicroVM (Firecracker, Kata Containers)** 기술 확산.
- **서버리스와의 연계**: 100ms 이하의 기동 속도가 필요한 AWS Lambda 등에서 MicroVM 기술을 통해 멀티테넌시 보안 확보.

## Ⅵ. 기술사 관점의 결론 및 제언
- 가상화는 **'격리(Isolation)'와 '성능(Performance)'**의 균형을 찾아가는 과정임.
- **실무 제언**: 인프라 설계 시 서비스의 성격에 따라 데이터베이스 등 고신뢰성 작업은 **VM**에, 웹 서비스나 마이크로서비스 등 탄력적 확장이 필요한 작업은 **컨테이너**에 배치하는 하이브리드 아키텍처 전략이 바람직함.
