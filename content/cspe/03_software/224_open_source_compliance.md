# 📖 【암기용】 개념 완전 이해

> 목적: 오픈소스 컴플라이언스를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 오픈소스 사용 시 라이선스·보안·출처·배포 의무를 조직 절차로 준수하는 활동
- **왜 필요한가**: 개발자가 패키지를 설치하는 순간 법적 의무와 취약점 관리 책임이 제품에 들어온다
- **핵심 직관**: 오픈소스 컴플라이언스는 "써도 되는지, 어떻게 고지할지, 취약점은 무엇인지"를 릴리스 전에 확인하는 관문이다

## 깊이 이해
- **배경·문제의식**: 현대 제품은 직접 작성 코드보다 외부 컴포넌트 비중이 크다. GitHub 코드 복사, transitive dependency, 컨테이너 base image는 개발자가 인지하지 못한 라이선스와 CVE를 포함할 수 있다.
- **작동 원리**: 정책 수립, SCA 스캔, SBOM 생성, 라이선스 승인, 취약점 예외 처리, NOTICE 생성, 릴리스 증적 보관 순서로 운영한다.
- **비유**: 식품 회사가 원재료 원산지, 알레르기 성분, 유통기한을 표시하듯 SW 제품도 구성요소와 의무를 표시해야 한다.
- **구체 예시**: 릴리스 파이프라인에서 GPL-3.0, AGPL-3.0, critical CVE가 발견되면 배포를 차단하고 법무·보안 예외 승인 기록을 남긴다.
- **흔한 오해·주의점**: 컴플라이언스는 법무팀만의 업무가 아니다. 개발, 보안, 법무, 구매, 릴리스 관리가 같은 SBOM과 승인 workflow를 사용해야 한다.

## 연결 개념
- Software License - 라이선스 유형과 배포 의무
- SBOM - 컴포넌트 목록과 증적
- SLSA - 빌드·출처·서명 기반 공급망 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 오픈소스 컴플라이언스는 라이선스 표기 활동이 아니라 정책, 자동 스캔, 승인, 배포 증적, 예외 관리 체계이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 오픈소스 컴플라이언스는 OSS 사용에 따른 라이선스·보안·출처·고지 의무를 릴리스 전에 검증하는 통제 체계이다.
> 2. **가치**: 법적 분쟁, 배포 중단, 취약점 미조치, 공급망 공격 영향을 정책과 증적으로 줄인다.
> 3. **판단 포인트**: SCA, SBOM, 승인 workflow, NOTICE, 예외 만료일, 감사 추적이 답안의 필수 축이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| OSS 거버넌스 이해 확인 | 정책, 역할, 도구, 릴리스 게이트 | 라이선스 종류만 나열 |
| 법적·보안 리스크 판단 확인 | GPL/AGPL, CVE, 출처, NOTICE | 취약점 관리와 라이선스 관리를 분리 설명 |
| 실무 프로세스 설계 확인 | SCA, SBOM, 승인, 예외, 증적 보관 | 예외 승인 만료일과 재검토 누락 |

> 요약: 이 문제는 OSS 사용 허용 여부를 개발 pipeline에서 판단하는 운영 체계를 요구한다.

## Ⅰ. 개요 및 필요성

오픈소스 컴플라이언스는 OSS 사용 의무 준수 체계이다. 제품에 포함된 라이브러리, 컨테이너 이미지, 코드 스니펫은 라이선스와 취약점을 함께 가져온다. 릴리스 전 식별·승인·고지·증적이 없으면 배포 중단과 감사 실패가 발생한다.

---

## Ⅱ. 구조 및 구성요소

```text
OSS Policy -> Developer Request -> SCA Scan
-> SBOM -> Legal/Security Review -> Approval/Exception
-> NOTICE/Source Offer -> Release Gate -> Evidence Store
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| OSS Policy | 허용·검토·금지 라이선스와 취약점 기준 | GPL, AGPL, critical CVE 기준 |
| SCA Tool | 의존성, 라이선스, CVE 자동 식별 | direct/transitive dependency 포함 |
| Review Board | 법무·보안·개발 승인 | 예외 만료일과 재검토 조건 |
| Evidence Store | SBOM, NOTICE, 승인 기록 보관 | 감사 대응 5영업일 목표 |

> 요약: 컴플라이언스 구조는 정책, 자동 식별, 합의 승인, 릴리스 증적 저장소로 구성된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
패키지 추가 -> CI SCA Scan -> License/CVE 분류
-> Policy Match -> 승인 또는 차단
-> NOTICE/SBOM 생성 -> Release Gate 통과
-> 사후 CVE 모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 신규 OSS 요청과 의존성 수집 | 패키지 누락 0건 |
| 2 | 라이선스·CVE 자동 분석 | SPDX 식별 100% |
| 3 | 위험 등급별 승인 처리 | high risk 승인 100% |
| 4 | 릴리스 산출물과 증적 보관 | NOTICE/SBOM 포함 100% |

> 요약: OSS 컴플라이언스는 개발 중 스캔하고 릴리스 전 차단·승인·증적을 완료하는 흐름이다.

## Ⅳ. 특징

| 구분 | 임의 OSS 사용 | Open Source Compliance | 판단 수치 |
|:---|:---|:---|:---|
| 식별 | 개발자 선언 의존 | SCA 자동 분석 | 의존성 식별률 100% |
| 법적 의무 | 릴리스 후 대응 | 라이선스 등급별 승인 | 고위험 승인 누락 0건 |
| 보안 | CVE 수동 확인 | CVE gate와 예외 만료 | critical CVE SLA 7일 |

> 요약: 컴플라이언스는 OSS 사용을 개발자 재량에서 조직 릴리스 통제로 전환한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | Open Source Compliance | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 사후 법무 검토 | CI gate와 승인 workflow | 월 릴리스 1회 이상 제품 |
| 비용/성능 | 릴리스 직전 지연 | 개발 중 자동 검출 | 정책 위반 피드백 10분 이하 |
| 운영/위험 | 의존성·고지 누락 | SBOM·NOTICE 자동 생성 | 감사 대응 5영업일 이하 |

> 요약: 릴리스 빈도가 높을수록 사후 검토 대신 CI 기반 컴플라이언스 게이트가 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 라이선스 위반 | GPL·AGPL 혼입 | 정책 차단, 법무 승인 | restricted license 0건 |
| 취약점 방치 | transitive CVE 미탐지 | SCA 지속 스캔, SLA | critical CVE 7일 내 조치 |
| 증적 부족 | NOTICE·SBOM 미생성 | release checklist 자동화 | 산출물 포함률 100% |

> 요약: 주요 리스크는 라이선스, CVE, 증적이며 CI gate와 만료일 기반 예외로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 정책 준수 | 금지 라이선스 0건 | SCA policy report |
| 예외 관리 | 예외 만료일 100% 등록 | workflow audit |
| 사후 모니터링 | 신규 critical CVE 24시간 내 알림 | vulnerability feed |

> 요약: 운영 수준은 금지 항목 차단, 예외 만료 관리, 신규 CVE 탐지 시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. OSS 정책을 허용, 검토, 금지 3단계로 정의하고 GPL/AGPL/SSPL/상용금지 조항은 릴리스 전 법무 승인 적용
2. SCA를 CI에 연결해 라이선스, CVE, transitive dependency를 검사하고 critical CVE는 7일 SLA로 처리
3. 릴리스마다 CycloneDX 또는 SPDX SBOM, NOTICE, source offer, 승인 기록을 생성해 감사 저장소에 보관

**결론 (2줄):**
- 기술사 판단: OSS 비중 30% 이상 또는 외부 배포 제품은 SCA와 SBOM 기반 컴플라이언스 게이트를 필수 통제로 적용
- 향후 방향: 오픈소스 컴플라이언스는 SLSA, 서명 검증, VEX와 결합되어 공급망 신뢰성 관리로 확장
