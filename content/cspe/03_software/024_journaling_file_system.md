## Ⅰ. 개요
- 정의: 데이터 변경 전 로그(Journal)를 먼저 기록하여 비정상 종료 시 빠른 복구를 지원하는 방식
- 배경: 시스템 크래시 후 전체 파일 시스템을 검사(fsck)하는 과도한 시간 소요 해결 필요
- 출제 의도: 저널링의 동작 메커니즘(Write-Ahead Logging)과 신뢰성 보장 원리 이해

## Ⅱ. 구성요소
```
[ Log/Journal Area ] -> [ Actual File System ]
(1. Record Intent)       (2. Execute Update)
       |                        |
       +------(Commit Check)----+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 저널 (Journal) | 메타데이터 또는 데이터의 변경 예정 사항을 담는 로그 영역 | 작업 전 메모 |
| 체크포인트 | 로그의 내용이 실제 저장소에 반영 완료된 시점 | 정산 완료 |
| 리플레이 | 부팅 시 저널의 로그를 읽어 미반영 작업을 재수행하는 과정 | 메모 보고 복구 |
> 요약: "먼저 쓰고, 나중에 옮긴다"는 원칙으로 일관성을 유지함.

## Ⅲ. 절차
```
[Tx Start] -> [Log Write] -> [Actual Update] -> [Tx Commit] -> [Log Delete]
```
1. 파일 쓰기 요청 발생 시 트랜잭션(Transaction)을 생성함
2. 변경될 정보를 저널 영역에 순차적으로 기록(Log write)
3. 실제 데이터 블록 및 메타데이터 영역에 내용 반영(Checkpointing)
4. 모든 작업이 안전하게 완료되면 저널의 해당 로그를 무효화(Commit)
> 요약: 장애 발생 시 저널에 기록된 유효 로그만 찾아 재수행(Redo)하여 복구함.

## Ⅳ. 문제점
- 원인: 메타데이터와 데이터를 모두 저널링할 경우 디스크 쓰기 부하가 2배로 증가함
- 원인: 저널 영역 자체가 물리적으로 손상될 경우 복구가 불가능한 치명적 결함 발생

## Ⅴ. 개선방안
- (단기) 메타데이터만 저널링하는 'Ordered 모드'를 사용하여 성능과 신뢰성 절충
- (중기) 저널 영역을 SSD 등 고속 저장장치에 별도 배치하여 I/O 성능 극대화
- (장기) 파일 시스템 수준이 아닌 스토리지 컨트롤러 수준의 원자적 쓰기 지원 활용

## Ⅵ. 전망
- 고성능 연산을 위해 비휘발성 메모리(NVM)를 저널 전용 공간으로 활용하는 연구 활발
- 데이터 무결성이 중요한 금융/엔터프라이즈 서버에서 저널링은 기본 사양으로 정착됨
