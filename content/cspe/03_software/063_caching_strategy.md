## Ⅰ. 개요
- 정의: 데이터 접근 속도 향상을 위해 저속 저장소 데이터를 고속 캐시에 미리 저장하는 기법.
- 출제 의도: 읽기/쓰기 빈도 및 데이터 무결성 요건에 따른 최적 캐싱 패턴 선택 능력 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  < Look-aside >                   < Write-through >
  [ App ] --(1)--> [ Cache ]        [ App ] --(1)--> [ Cache ]
    | (3) Miss       | (2) Hit        |               | (2) Sync
    v                v                v               v
  [ DB ] <----------+               [ DB ] <---------+
- 구성요소 표
| 전략 | 설명 | 비유 |
| :--- | :--- | :--- |
| Look-aside | 캐시 확인 후 없으면 DB 조회 및 캐시 갱신 (읽기 위주) | 단골 식당 메뉴판 확인 |
| Write-through | 캐시와 DB를 동시에 업데이트 (쓰기 위주) | 이중 장부 기록 |
| Write-behind | 캐시에만 먼저 쓰고 나중에 DB에 일괄 반영 | 가계부 몰아서 쓰기 |
> 요약: 성능 우선(Look-aside)이냐, 정합성 우선(Write-through)이냐의 선택임.

## Ⅲ. 절차
- ASCII 흐름도
  [요청] -> [캐시 히트 확인] -> [처리(Hit/Miss)] -> [데이터 동기화]
- 4단계 설명
1. 애플리케이션이 데이터를 요청할 때 가장 먼저 캐시 메모리를 조회함.
2. 데이터가 있으면(Hit) 즉시 반환하고, 없으면(Miss) DB에서 직접 읽음.
3. DB에서 읽은 최신 데이터를 향후 요청을 위해 캐시에 다시 적재함.
4. 데이터 수정 시 설정된 전략에 따라 캐시 무효화나 업데이트를 수행함.
> 요약: 빈번한 DB 접근을 줄여 응답 속도를 개선하고 시스템 부하를 경감함.

## Ⅳ. 문제점
- 데이터 불일치: 캐시의 데이터가 DB의 실제 값과 달라지는 'Dirty Cache' 현상 발생함.
- 캐시 쇄도 (Stampede): 캐시 만료 시 다수의 요청이 동시에 DB로 몰려 서버 다운됨.

## Ⅴ. 개선방안
- TTL 설정: 데이터의 특성에 맞는 적절한 유효기간(Time To Live) 부여함.
- 확률적 만료 (PER): 만료 직전에 미리 백그라운드에서 캐시를 갱신하여 쇄도 방지함.

## Ⅵ. 전망
- 클라우드 엣지(Edge) 캐싱이 고도화되어 사용자 물리적 거리 기반의 캐싱 기술 보편화됨.
- AI가 트래픽 패턴을 분석하여 어떤 데이터를 미리 캐싱할지 결정하는 지능형 캐시 운영됨.
- 글로벌 분산 캐시 기술을 통해 국가 간 데이터 접근 지연 시간을 최소화하는 아키텍처 확산됨.
