## Ⅰ. 개요
- **정의**: 소스 코드를 실행하는 두 가지 방식으로, 인터프리터는 한 줄씩 해석·실행하고 컴파일러는 전체를 기계어로 변환 후 실행함
- **배경/필요성**: 개발 편의성과 실행 성능 간 트레이드오프를 이해해야 언어·플랫폼 선택 시 합리적 판단이 가능함
- **비유**: 동시통역(인터프리터)과 사전 번역 출판(컴파일러)의 차이와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 방식의 차이와 적용 시나리오 구분 | 번역 시점·실행 속도·오류 검출 시점 비교 | 현대 언어는 혼합 방식(JIT 등)을 사용한다는 점 언급 |

> 요약: 번역 시점과 실행 방식의 차이로 개발 편의성과 실행 성능 간 트레이드오프가 발생함

## Ⅱ. 구성요소
```text
[Interpreter]                    [Compiler]
Source --+                       Source --+
         |                                |
    Read line                        Lexical Anal.
         |                                |
    Execute                          Syntax Anal.
         |                                |
    Next line                        Code Gen
         |                                |
    (repeat)                         Object File
                                          |
                                     Execute
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 인터프리터 | 소스를 한 문장씩 읽어 즉시 실행, 별도 목적 파일 미생성 | 동시통역사가 말하는 즉시 번역 |
| 컴파일러 | 소스 전체를 분석·변환하여 독립 실행 가능한 목적 파일 생성 | 원서를 완역 출판 후 독자가 읽음 |
| 하이브리드 | 바이트코드 컴파일 후 VM에서 인터프리트 또는 JIT 컴파일(184 참조) | 초벌 번역 후 필요 부분만 정밀 번역 |

> 요약: 해석 즉시 실행, 일괄 변환 후 실행, 두 방식의 혼합으로 분류됨

## Ⅲ. 절차
```text
[Interpreter] Read --> Parse --> Execute --> Next Statement (반복)
[Compiler]    Lex --> Parse --> Optimize --> CodeGen --> Link --> Execute
```
- 1단계: 소스 입력 — 인터프리터는 한 문장, 컴파일러는 전체 파일 단위로 읽음
- 2단계: 구문 분석 — 인터프리터는 즉시 AST 평가, 컴파일러는 전체 AST 구성
- 3단계: 실행/변환 — 인터프리터는 평가 결과 즉시 실행, 컴파일러는 최적화 후 목적 코드 생성(181, 182 참조)
- 4단계: 반복/링크 — 인터프리터는 다음 문장으로 이동, 컴파일러는 링커로 실행 파일 생성

> 요약: 인터프리터는 문장 단위 반복, 컴파일러는 전체 변환 후 일괄 실행하는 흐름임

## Ⅳ. 문제점
- 인터프리터 성능 한계: 매 실행 시 반복 해석 오버헤드 발생 — 연산 집약 작업에 부적합
- 컴파일러 개발 지연: 전체 컴파일 후 실행하므로 수정-실행 사이클이 길어짐 — 프로토타이핑 속도 저하
- 오류 검출 시점 차이: 인터프리터는 런타임까지 타입 오류가 지연되고, 컴파일러는 컴파일 타임에 검출하나 동적 오류 대응 곤란

> 요약: 실행 성능, 개발 사이클, 오류 검출 시점에서 각각 한계가 존재함

## Ⅴ. 개선방안
1. 단기: 인터프리터에 바이트코드 캐싱 도입으로 반복 해석 오버헤드 감소
2. 중기: 증분 컴파일(Incremental Compilation) 적용으로 수정된 모듈만 재컴파일하여 빌드 시간 단축
3. 장기: JIT/AOT 혼합 런타임(184, 185 참조) 도입으로 동적 최적화와 사전 컴파일 장점을 동시 확보

> 요약: 캐싱·증분 컴파일·하이브리드 런타임으로 양측 단점을 보완함

## Ⅵ. 전망
- 발전 방향: 대부분의 현대 언어가 컴파일-인터프리트 혼합 모델을 채택하는 추세임
- 기술사적 판단: 클라우드·엣지 환경에서 시작 시간과 피크 성능 모두 요구되어 혼합 전략의 중요성 증가
- 기술사 제언: 워크로드 특성에 따라 인터프리트·JIT·AOT를 선택적으로 적용하는 적응형 실행 전략 수립이 필요함
