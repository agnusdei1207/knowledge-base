## Ⅰ. 개요
- 소프트웨어를 독립된 기능을 가진 모듈로 분할하여 관리하는 기법임.
- 품질 척도로서 결합도(Coupling)는 낮추고 응집도(Cohesion)는 높여야 함.
- 출제 의도: 모듈의 독립성 확보를 위한 평가 지표별 상세 단계 이해 확인.

## Ⅱ. 구성요소
- 결합도 및 응집도 척도
[High Cohesion] <---> [Low Coupling]

| 구성요소 | 설명 | 평가 방향 |
| :--- | :--- | :--- |
| Cohesion (응집도) | 모듈 내부 요소들이 얼마나 밀접하게 관련되어 있는지 | 높을수록 좋음 |
| Coupling (결합도) | 모듈 간 상호 의존 관계가 얼마나 긴밀한지 | 낮을수록 좋음 |
| Information Hiding | 내부 구현을 숨기고 인터페이스만 노출함 | 캡슐화 |
> 요약: 독립성이 높은 모듈은 수정이 용이하고 재사용성이 뛰어남.

## Ⅲ. 절차
- 모듈화 설계 단계 (Best -> Worst)
[Functional Cohesion] -> [Logical] | [Content Coupling] <- [Data]

1. 응집도 강화: 우연적 -> 논리적 -> 절차적 -> 통신적 -> 순차적 -> 기능적 응집.
2. 결합도 약화: 내용 -> 공통 -> 외부 -> 제어 -> 스탬프 -> 자료 결합.
3. 인터페이스 정의: 필요한 매개변수만 최소한으로 전달하도록 설계함.
4. 검증: 모듈 변경 시 영향도를 분석하여 독립성 수준을 평가함.
> 요약: 기능 중심으로 모듈을 묶고, 순수 데이터 전달 방식으로 연결함.

## Ⅳ. 문제점
- 과도한 모듈 분할로 인한 모듈 간 통신 비용 및 전체 구조 파악 어려움.

## Ⅴ. 개선방안
- 적정 수준의 모듈 크기(Granularity) 산정과 공통 모듈 라이브러리화.

## Ⅵ. 전망
- 마이크로서비스 간의 느슨한 결합을 보장하는 서비스 메쉬(Service Mesh) 확산.
- 정적 코드 분석 도구를 통한 결합도/응집도 자동 측정 및 관리 체계 정착.
