## Ⅰ. 개요
- **정의**: 실행 중인 애플리케이션에 외부 입력을 주입하여 보안 취약점을 탐지하는 기법
- **배경/필요성**: 런타임 환경에서만 발현되는 인증·권한·설정 결함 탐지가 필요함
- **비유**: 완성된 건물에 실제로 침입을 시도하여 방어 허점을 찾는 모의 훈련과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SAST(282)와 비교 출제 빈출 | 블랙박스·런타임 기반 탐지 | 소스코드 불필요·취약점 위치 특정 어려움 명시 |

> 요약: 실행 환경에서 외부 공격을 모사하여 런타임 보안 결함을 탐지하는 기법임

## Ⅱ. 구성요소
```text
Target App <-- HTTP Request -- Crawler/Scanner
     |                              |
     +-----> HTTP Response -------->+
                                    v
                             취약점 리포트
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 크롤러 | 애플리케이션 URL·파라미터를 자동 탐색하여 공격 표면 수집 | 건물 출입구 전수 조사 |
| 스캐너 | SQL Injection·XSS 등 공격 패턴 입력을 자동 주입 | 각 출입구에 침입 시도 |
| 응답 분석기 | HTTP 응답 코드·본문·시간을 분석하여 취약 여부 판정 | 침입 성공 여부 확인 |
| 리포트 생성기 | 탐지 취약점·재현 요청·심각도 등급 출력 | 침입 결과 보고서 |

> 요약: 크롤링→공격 주입→응답 분석→리포트의 블랙박스 보안 테스트 체계임

## Ⅲ. 절차
```text
대상 배포 --> 크롤링 --> 공격 주입 --> 결과 검증
```
- 1단계: 테스트 대상 애플리케이션을 스테이징 환경에 배포
- 2단계: 크롤러가 URL·폼·API 엔드포인트 자동 탐색
- 3단계: OWASP Top 10 기반 공격 페이로드 자동 주입 및 응답 수집
- 4단계: 탐지 결과 검증 후 참양성 취약점에 대해 수정 조치

> 요약: 배포→크롤링→공격→검증 순서로 런타임 취약점을 식별·수정함

## Ⅳ. 문제점
- 취약점 위치 미특정: 소스코드 접근 없이 외부 관찰만 수행 — 결함 코드 라인 식별 불가
- 인증 후 영역 한계: 로그인 필수 페이지 크롤링 실패 — 테스트 범위 누락 발생
- 테스트 시간 과다: 대규모 애플리케이션 전수 스캔 시 수 시간 소요 — CI 파이프라인 지연

> 요약: 위치 미특정·인증 영역 누락·장시간 소요가 주요 한계임

## Ⅴ. 개선방안
1. 단기: SAST(282) 결과와 매핑하여 취약점 코드 위치 상호 보완
2. 중기: 인증 토큰 자동 주입·세션 관리 기능으로 인증 후 영역 커버리지 확대
3. 장기: 증분 스캔·병렬 스캔 기법 도입으로 스캔 시간 단축

> 요약: SAST 연계·인증 자동화·증분 스캔으로 DAST 한계 극복 필요

## Ⅵ. 전망
- 발전 방향: IAST(Interactive AST)로 SAST+DAST 결합형 분석 확산
- 기술사적 판단: API 보안 테스트 수요 증가로 REST/GraphQL 전용 DAST 도구 성장 중임
- 기술사 제언: SAST·DAST·SCA(284) 통합 파이프라인 구축으로 보안 테스트 자동화 필요
