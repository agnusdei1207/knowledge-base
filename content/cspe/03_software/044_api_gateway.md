## 미리 알고가기

- API 게이트웨이는 외부 요청의 단일 진입점 역할을 하는 중간 계층임
- 인증과 라우팅과 rate limiting과 응답 조합이 주요 기능임
- 모든 기능을 게이트웨이에 몰아넣으면 병목과 비대화가 생길 수 있음

## Ⅰ. 개요

- **정의/개념**: API 게이트웨이는 클라이언트 요청을 받아 적절한 내부 서비스로 라우팅하고 인증과 정책 적용과 응답 조합을 수행하는 API 진입 제어 계층임
- **배경/필요성**: 마이크로서비스 환경에서는 클라이언트가 다수 서비스와 직접 통신하면 인증과 버전 관리와 라우팅 복잡도가 커지므로, 이를 앞단에서 통합 관리할 계층이 필요함

## Ⅱ. 특징

- 클라이언트와 내부 서비스 사이 결합을 줄이고 정책 집행 지점을 단일화함
- 인증과 rate limiting과 버전 관리와 로깅을 공통 처리할 수 있음
- 응답 조합과 변환 기능으로 클라이언트별 API를 최적화할 수 있음
- 지나친 비즈니스 로직 집중은 게이트웨이를 새로운 모놀리스로 만들 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 서비스 호출 | API 게이트웨이 사용 |
|:---|:---|:---|
| 클라이언트 복잡도 | 각 서비스별 처리 필요 | 단일 엔드포인트 중심 |
| 공통 정책 | 서비스별 중복 구현 | 중앙 정책 적용 가능 |
| 장점 | 단순 경로, 중간 계층 없음 | 인증과 라우팅 통합 관리 |
| 한계 | 변경 영향 크고 중복 증가 | 병목과 단일 장애점 가능 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Routing Layer | 요청 경로와 버전에 따라 대상 서비스를 결정해 진입 제어의 중심 역할을 함 |
| Auth and Policy Filter | 인증과 권한과 rate limiting을 공통 적용해 보안과 사용량 통제를 일관되게 유지함 |
| Aggregation or Transformation | 여러 서비스 응답을 조합하거나 형식을 변환해 클라이언트 최적화를 돕음 |
| Observability Hook | 로깅과 추적과 메트릭 수집을 통해 API 사용량과 장애 원인을 드러냄 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요청 수신      | --> | 인증/정책 적용 | --> | 서비스 라우팅  | --> | 응답 반환      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요청 수신**: 클라이언트 호출을 단일 진입점에서 받음
2. **인증 및 정책 적용**: 토큰 검증과 권한과 rate limiting을 수행함
3. **서비스 라우팅**: 대상 서비스로 요청을 전달하거나 여러 응답을 조합함
4. **응답 반환**: 변환과 로깅을 마친 뒤 결과를 반환함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 비즈니스 조합 로직이 과도하게 쌓이면 게이트웨이 자체가 복잡한 병목 서비스가 될 수 있음
   - 해결방안: 정책과 조합 범위를 제한하고 gateway complexity score와 gateway latency로 검증함
2. 문제: 단일 진입점 장애는 다수 서비스 접근 불능으로 번질 수 있음
   - 해결방안: 이중화와 autoscaling과 graceful degradation을 적용하고 gateway availability와 failover success rate로 검증함
3. 문제: 서비스별 예외 처리와 에러 매핑이 일관되지 않으면 클라이언트 경험이 불안정해질 수 있음
   - 해결방안: 표준 오류 계약을 운영하고 error schema consistency와 client retry failure rate로 검증함

## Ⅶ. 적용 사례

- 모바일 백엔드에서는 API 게이트웨이를 사용하고 확인 지표는 gateway latency와 error schema consistency임
- B2B API 플랫폼에서는 인증과 rate limiting을 게이트웨이에서 처리하고 확인 지표는 gateway availability와 policy violation block rate임
- 마이크로서비스 통합 환경에서는 응답 조합을 제한적으로 적용하고 확인 지표는 gateway complexity score와 client retry failure rate임

## Ⅷ. 결론

API 게이트웨이의 가치는 엔드포인트를 하나로 만드는 데 있지 않고 공통 정책과 진입 복잡도를 통제하면서도 비즈니스 로직 과집중을 막는 균형에 있음.
