## 핵심 인사이트 (3줄 요약)
- 마이크로서비스 아키텍처(MSA)에서 외부 클라이언트의 모든 요청을 단일 진입점(Single Entry Point)으로 받아 내부 서비스로 라우팅하는 프록시 서버.
- 라우팅뿐만 아니라 인증/인가, 로드 밸런싱, 로깅, 요금 제한(Rate Limiting) 등 서비스들의 '공통 관심사'를 한 곳에서 중앙 통제함.
- 게이트웨이 자체가 단일 장애점(SPOF)이 될 수 있으므로, 고가용성 설계와 BFF(Backend for Frontend) 패턴을 통한 부하 분산이 필수적임.

## Ⅰ. 개요 및 필요성
- **개요**: 클라이언트와 수많은 백엔드 마이크로서비스 사이에 위치하여 트래픽을 제어하고 API를 관리하는 미들웨어.
- **필요성**: MSA 환경에서는 수십~수백 개의 서비스가 각기 다른 주소(IP/Port)를 가짐. 클라이언트가 이를 다 알고 직접 호출하면 커플링이 심해지고, 서비스마다 인증 로직을 중복 구현해야 하는 심각한 비효율이 발생함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **API 게이트웨이의 핵심 기능**:
  1. **라우팅 (Routing)**: URL Path나 Header를 분석해 적절한 백엔드 서비스로 요청 전달.
  2. **API 조합 (Aggregation)**: 클라이언트의 한 번 호출로 내부의 여러 API를 찔러 데이터를 모아서 반환 (오버페칭 방지).
  3. **공통 처리 (Cross-Cutting Concerns)**: JWT 토큰 검증, SSL 터미네이션, 로깅, CORS 설정.
  4. **트래픽 제어**: Rate Limiting(속도 제한), Circuit Breaker(서킷 브레이커)를 통한 백엔드 보호.

```text
[ API Gateway 아키텍처 흐름도 ]

 (Mobile/Web)       [ 단일 진입점 ]                (내부 마이크로서비스)
                 +-------------------+          +-------------------+
    요청 1  ➡️   |                   | --라우팅->|  Order Service    |
                 |   API Gateway     |          +-------------------+
    요청 2  ➡️   | (인증, 라우팅,    | --조합--->|  User Service     |
                 |  로깅, Rate Limit)|          +-------------------+
                 +-------------------+          +-------------------+
```

## Ⅲ. 비교 및 연결
| 구분 | 리버스 프록시 (Nginx/HAProxy) | API Gateway (Spring Cloud Gateway, Kong) | BFF (Backend for Frontend) |
|---|---|---|---|
| **목적** | 트래픽 전달 및 부하 분산 | API 관리 및 공통 비즈니스 로직(인증) 통제 | 특정 클라이언트(Web/모바일) 맞춤형 API 조합 |
| **추상화 수준**| L4 ~ L7 수준의 네트워크 라우팅 | L7 중심, 토큰 파싱 등 어플리케이션 계층 제어 | UI에 핏을 맞추기 위한 비즈니스 로직 포함 |
| **복잡도** | 낮음 | 중간 (다양한 필터 파이프라인) | 높음 (클라이언트별 다수 존재) |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **BFF (Backend for Frontend) 도입**: 모든 트래픽을 1개의 범용 게이트웨이로만 몰아넣으면 병목이 발생함. 실무에서는 모바일용 게이트웨이, 웹용 게이트웨이(BFF)를 따로 두어 각 프론트엔드에 최적화된 API 조합을 제공하는 설계가 권장됨.
- **무거운 로직 금지**: 게이트웨이는 철저히 트래픽을 넘기는 파이프 역할만 해야 함. 여기에 복잡한 비즈니스 로직이나 무거운 DB 조회를 넣으면 전체 시스템의 응답 속도를 갉아먹는 최악의 병목 구간이 됨.
---
## Ⅴ. 기대효과 및 결론
- 클라이언트는 내부 마이크로서비스의 물리적 위치(IP)나 분할 상태를 전혀 알 필요 없이 단일 도메인만 바라보면 되므로(캡슐화), 백엔드 리팩토링과 확장이 극도로 자유로워짐.
- 결론적으로 API Gateway는 MSA의 '현관문'이자 '보안요원'으로, 클라우드 네이티브 아키텍처를 지탱하는 가장 필수적인 미들웨어 인프라임.

### 👶 어린이를 위한 3줄 비유 설명
1. 큰 병원에 가면 내가 내과를 가야 할지 외과를 가야 할지 헷갈리죠? 
2. API 게이트웨이는 병원 입구에 있는 '안내 데스크'와 같아요. 
3. "배가 아파요"라고 안내 데스크에 말하면 신분증(인증)을 확인하고, 내과 의사 선생님(서비스)에게 바로 안내해 주는 친절한 역할을 한답니다.
