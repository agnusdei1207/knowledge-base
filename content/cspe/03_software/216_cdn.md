# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 지리적으로 분산된 여러 캐시 서버(Edge Server)를 통해 사용자에게 웹 콘텐츠를 빠르고 안정적으로 전송하는 네트워크 인프라
- **왜 필요한가**: 한국에 있는 서버의 이미지를 미국 사용자가 요청하면 태평양 해저 케이블을 건너야 해서 느리다. 사용자 가까운 곳에 복사본을 두어 속도를 높이고 원본 서버 부하를 줄이기 위함이다.
- **핵심 직관**: 글로벌 물류 창고. 본사 공장(Origin)에서 매번 택배를 보내지 않고, 각 지역 물류센터(Edge)에 물건을 미리 갖다 두고 주문 즉시 동네에서 배송한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Origin Server (원본 서버) | 원본 콘텐츠를 가지고 있는 실제 백엔드 서버 | 본사 메인 공장 |
| Edge Server (PoP) | 사용자와 물리적으로 가까운 곳에 배치된 캐시 서버 무리 (Point of Presence) | 각 지역 거점 물류센터 |
| TTL (Time to Live) | 에지 서버가 콘텐츠를 캐싱하고 있는 유효 시간 | 유통 기한 |
| Anycast | 가장 가까운 노드로 트래픽을 라우팅하는 네트워크 라우팅 기법 | 112 누르면 가장 가까운 경찰서 연결 |

## 깊이 이해
- **배경·문제의식**: 고용량 미디어, 글로벌 서비스 확대로 인해 원본 서버 단일 지점에서 트래픽을 감당하면 1) 대역폭 비용 폭발 2) 지리적 네트워크 지연(Latency) 3) 디도스(DDoS) 공격 시 단일 장애점 발생이라는 문제가 생긴다.
- **작동 원리**:
  1. 사용자가 `image.jpg` 요청 시 DNS가 가장 지리적으로 가까운 CDN 에지 서버의 IP를 반환한다 (Anycast 기반).
  2. 에지 서버에 캐시가 있으면 즉시 반환 (Cache Hit).
  3. 없으면(Miss) 원본 서버(Origin)에 요청하여 가져온 뒤, 사용자에게 주고 자신도 캐싱한다.
- **비유**: 편의점(Edge)에 빵(콘텐츠)이 있으면 바로 사고, 없으면 본사(Origin)에 발주 넣어서 가져온 다음 며칠간 진열해두는 원리.
- **구체 예시**: 넷플릭스 영상 시청 시, 미국 서버에서 직접 스트리밍되는 것이 아니라 통신사(SKT, KT) 내부에 설치된 넷플릭스 에지 서버(Open Connect)에서 쏴준다.
- **흔한 오해·주의점**: CDN은 정적 이미지/영상만 처리한다고 생각하기 쉬우나, 최신 CDN은 동적 API 캐싱, WAF(방화벽) 탑재, 에지 컴퓨팅(Edge Worker)을 통한 인증/로직 처리까지 수행하는 클라우드 보안·컴퓨팅 플랫폼으로 진화했다.

## 연결 개념
- 로드 밸런싱 전략
- 캐싱 전략
- 디도스(DDoS) 방어

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 지리적으로 분산된 에지(Edge) 노드에 콘텐츠를 캐싱하여, 엔드유저와 서버 간의 물리적 네트워크 지연을 극복하는 분산 전송 아키텍처다.
> 2. **가치**: 백엔드 Origin 서버의 트래픽 부하와 대역폭 비용을 획기적으로 절감하며, 대규모 글로벌 트래픽 급증 및 DDoS 공격을 엣지 계층에서 흡수한다.
> 3. **판단 포인트**: 정적 자산(Static) 캐싱을 넘어, 동적(Dynamic) API 최적화와 에지 컴퓨팅(Edge Computing)을 결합한 통합 전송/보안 계층으로 활용해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 글로벌 트래픽 분산 및 가용성 확보 이해 | Origin, Edge(PoP), DNS 라우팅, Cache Hit/Miss 흐름 | CDN을 단순 저장소로 서술 |
| 최신 CDN의 확장 역할(보안, 컴퓨팅) 인지 | WAF 통합 방어(DDoS), 동적 콘텐츠 전송 가속, Edge Worker | 정적 이미지 캐싱 기능에만 한정 |

> 요약: CDN의 기본인 정적 캐싱 전송 흐름을 명확히 하고, 보안(WAF)과 엣지 로직(Worker)을 포함한 현대적 아키텍처 관점을 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 사용자와 지리적으로 인접한 에지(Edge) 서버들의 분산 네트워크를 통해 웹 콘텐츠를 고속으로 전송하는 인프라
- 배경: 글로벌 서비스 확대 및 고화질 미디어 수요 급증으로 인해, 단일 Origin 서버 기반 아키텍처는 네트워크 병목과 고비용 발생
- 필요성: 네트워크 지연(Latency) 최소화, 서버 대역폭 비용(Egress) 절감, 대규모 트래픽 스파이크 방어

---

## Ⅱ. 구조 및 구성요소

```text
클라이언트 -> (DNS Anycast) -> CDN Edge Server (PoP)
                                  | (Cache Miss)
                                  +-> Origin Server (원본 백엔드)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Origin Server | 콘텐츠의 원본을 호스팅하고 관리하는 중앙 서버 | AWS S3 또는 자체 백엔드 WAS |
| Edge Server (PoP) | 사용자와 가까운 지리적 거점에 위치한 캐시 및 라우팅 노드 | 대륙별, ISP별 분산 배치 |
| DNS / Anycast | 클라이언트 위치 기반으로 최적의 물리적 Edge IP 반환 | Global Load Balancing 역할 |
| CDN Control Plane | 캐시 무효화(Purge), TTL 정책, 보안 규칙 설정 등 중앙 관리 | 실시간 토폴로지 동기화 |

> 요약: DNS 라우팅을 통해 최적의 에지 노드로 연결하고, 에지와 원본 서버 간 계층적 캐싱을 통해 트래픽을 처리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 요청 -> DNS 기반 Edge 라우팅 -> Cache Hit 여부 판별 -> (Miss 시) Origin 조회 -> 반환 및 캐싱
```

- 1단계 [위치 기반 라우팅]: 사용자가 도메인 질의 시, DNS(Anycast)가 지연 시간이 가장 짧은 Edge 노드 IP 매핑
- 2단계 [상태 판별]: 해당 Edge 노드가 캐시(Valid TTL)를 보유(Cache Hit)하고 있는지 검사
- 3단계 [원본 조회 및 갱신]: Miss 발생 시 Edge가 Origin 서버에 콘텐츠를 요청하고 전달받아 저장
- 4단계 [전달 및 방어]: 사용자에게 고속 전송하며, 악성 트래픽(DDoS) 진입 시 Edge 레벨에서 차단(WAF)

> 요약: 요청이 발생하면 지리적 라우팅, 상태 갱신, 보안 필터링을 거쳐 응답 속도를 극대화하는 메커니즘이다.

---

## Ⅳ. 특징
- 물리적 한계 극복: 대륙 간 해저 케이블 전송 지연을 로컬 ISP 내 Edge 라우팅으로 전환하여 Time-To-First-Byte(TTFB) 단축
- 비가용성 완충: Origin 서버가 장애(Down) 상태여도, Edge에 캐싱된 콘텐츠는 정상 서비스되어 가용성 향상
- 트래픽 쉴드(Shield): 대규모 DDoS 공격 트래픽을 Origin이 아닌 수천 대의 Edge 네트워크 용량으로 분산 흡수

> 요약: 속도 가속은 물론이며 인프라 비용 절감과 보안 방어막 역할을 동시에 수행하는 필수 프론트 계층이다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정적 캐싱 (Static Delivery) | 동적 가속 (Dynamic Acceleration) | 엣지 컴퓨팅 (Edge Worker) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 대상 데이터 | 이미지, CSS, JS, 동영상 | API JSON, 개인화된 HTML | 경량 비즈니스 로직 연산 | 콘텐츠 성격 |
| 전송 메커니즘 | Edge 캐시에 일정 시간(TTL) 보관 | BGP 라우팅 최적화, TCP 연결 재사용 | Edge 노드에서 직접 코드(JS, WASM) 실행 | 아키텍처 목적 |
| 혜택 | 대역폭 최적화 및 로딩 가속 | Origin 도달 네트워크 지연 시간 단축 | 백엔드 부하 감소 및 초저지연 연산 | 기대 효과 |

> 요약: 단순히 이미지를 캐싱하는 단계를 넘어, API 통신 최적화와 엣지 컴퓨팅을 도입하는 방향으로 설계해야 한다.

**리스크·대응 (기본은 불릿):**
- 캐시 갱신 지연 (Stale Content): 배포 후 낡은 파일 지속 노출 → 버전 번호 파라미터(Cache Buster) 삽입 및 명시적 Purge API 연동 (지표: 구버전 리소스 요청률)
- 캐시 스탬피드 및 Origin 과부하: 만료 시점에 대량의 Edge가 동시 Origin 찌름 → Origin Shield(중간 계층 Edge) 적용 및 Collapsed Forwarding 설정 (지표: Origin 5xx 에러율)
- 민감 데이터 노출: 개인정보가 포함된 API 응답이 전체 Edge에 캐싱 → Cache-Control 헤더 엄격 분리(Private/No-Cache) 통제 (지표: 보안 취약점 점검 결과)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 보안(WAAP) 통합 계층화: CDN Edge에 WAF(웹 방화벽)와 Bot Management 기능을 켜서 악성 트래픽이 백엔드 VPC 내부로 진입하기 전 원천 차단
2. 동적 이미지 최적화 엣지 구현: Origin에는 원본 이미지만 두고, Edge Worker(Lambda@Edge 등)를 통해 클라이언트 디바이스(WebP, 크기)에 맞춰 실시간 리사이징 전송
3. 멀티 CDN 전략 구성: 특정 CDN 벤더 장애(SPOF)에 대비해 DNS 레벨(Route53 등)에서 가용성과 지연 시간에 따라 2개 이상의 CDN으로 트래픽을 동적 라우팅

**결론:**
- 기술사 판단: 고비용의 인프라 스케일 아웃(Scale-Out) 이전에 CDN 레벨의 Cache Hit Ratio를 5%만 개선해도 전체 서버 비용과 장애 리스크를 절반으로 줄일 수 있다.
- 향후 방향: CDN은 단순 전송망을 넘어 5G MEC(Mobile Edge Computing)와 결합하여 자율주행, IoT 등 초저지연 로직 연산 플랫폼으로 패러다임이 진화하고 있다.
