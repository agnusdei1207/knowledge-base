## Ⅰ. 개요
- **정의**: 지리적으로 분산된 엣지 서버를 통해 콘텐츠를 사용자 근접 위치에서 제공하는 네트워크
- **배경/필요성**: 원본 서버와 사용자 간 물리적 거리가 멀수록 네트워크 지연이 증가하고 원본 부하가 집중됨
- **비유**: 본사 창고 대신 동네 편의점에서 상품을 바로 수령하는 구조

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CDN 캐싱 메커니즘과 무효화 전략 | 엣지 캐시 + 오리진 풀백 구조 | 동적 콘텐츠 가속(DSA)도 CDN 영역임을 언급 |

> 요약: 엣지 캐싱으로 지연을 줄이고 원본 부하를 분산하는 콘텐츠 전송 인프라임

## Ⅱ. 구성요소
```text
User --> Edge Server(PoP) --Cache Hit--> Return
              |
           Cache Miss
              |
              v
         Origin Server --Response--> Edge(캐시 저장) --> User
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Edge Server(PoP) | 사용자 인접 지역에 위치한 캐시 서버 | 동네 편의점 |
| Origin Server | 원본 콘텐츠를 보유한 중앙 서버 | 본사 창고 |
| Cache Purge | 콘텐츠 갱신 시 엣지 캐시를 무효화하는 메커니즘 | 재고 회수 통보 |

> 요약: 엣지-오리진 2계층 구조에서 캐시와 퍼지로 콘텐츠를 관리함

## Ⅲ. 절차
```text
DNS 해석 --> Edge 라우팅 --> Cache 판정 --> 콘텐츠 전달
```
- 1단계: DNS 해석 — 사용자 DNS 요청을 CDN의 글로벌 DNS가 최적 PoP IP로 응답
- 2단계: Edge 라우팅 — Anycast 또는 지리 기반으로 가장 가까운 엣지 서버에 도달
- 3단계: Cache 판정 — 엣지에 유효 캐시 존재 시 즉시 반환, 미스 시 오리진에 요청
- 4단계: 콘텐츠 전달 — 응답을 사용자에게 전송하고 엣지에 캐시 저장

> 요약: DNS-라우팅-캐시판정-전달의 4단계로 콘텐츠를 가속 제공함

## Ⅳ. 문제점
- 캐시 일관성: 오리진 갱신과 엣지 캐시 간 시간차로 구버전 콘텐츠가 제공됨
- 비용 증가: 글로벌 PoP 유지 및 대역폭 과금으로 트래픽 비례 비용이 상승함
- 동적 콘텐츠 한계: 개인화·실시간 데이터는 캐시 효율이 낮음

> 요약: 일관성, 비용, 동적 콘텐츠 처리가 주요 과제임

## Ⅴ. 개선방안
1. 단기: 버전 해시 기반 URL 무효화로 캐시 일관성 즉시 확보
2. 중기: 트래픽 분석 기반 PoP 선별 운영으로 비용 최적화
3. 장기: 엣지 컴퓨팅(Edge Function) 도입으로 동적 콘텐츠를 엣지에서 생성

> 요약: URL 버저닝, PoP 최적화, 엣지 컴퓨팅 순으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 엣지 컴퓨팅과 결합하여 CDN이 연산 플랫폼으로 진화하는 추세
- 기술사적 판단: 정적 가속을 넘어 API 가속·보안(DDoS 차단)까지 CDN 역할이 확장됨
- 기술사 제언: 멀티CDN 전략과 오리진 실드 계층 설계를 아키텍처에 반영할 필요
