## Ⅰ. 개요
- 정의: 웹 시스템을 논리적/물리적 역할에 따라 계층(Tier)으로 분리하여 구축하는 구조.
- 출제 의도: 계층 간 독립성 확보를 통한 유지보수 용이성 및 확장성 설계 역량 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Presentation Tier ] (Web Server / Browser)
           | (HTTP)
  [ Application Tier ]  (WAS / Business Logic)
           | (SQL/API)
  [ Data Tier ]         (Database / Storage)
- 구성요소 표
| 계층 | 설명 | 비유 |
| :--- | :--- | :--- |
| 프레젠테이션 | 사용자 인터페이스 제공 및 정적 컨텐츠 처리 | 카운터/접객 |
| 애플리케이션 | 실제 비즈니스 로직 및 동적 데이터 처리 | 주방/요리 |
| 데이터 | 데이터의 영구 저장 및 관리 (RDBMS, NoSQL 등) | 식재료 창고 |
> 요약: 각 계층은 하위 계층에만 의존하며 인터페이스를 통해서만 통신함.

## Ⅲ. 절차
- ASCII 흐름도
  [Request] -> [L7 LB] -> [Web Server] -> [WAS] -> [DB Query]
- 4단계 설명
1. 클라이언트의 요청이 로드밸런서를 거쳐 웹 서버로 전달됨.
2. 정적 자원은 웹 서버가 즉시 응답하고, 동적 요청은 WAS로 위임함.
3. WAS는 비즈니스 규칙에 따라 필요한 데이터를 DB에서 조회/가공함.
4. 최종 처리 결과를 응답 객체에 담아 역순으로 사용자에게 반환함.
> 요약: 요청이 각 계층을 순차적으로 통과하며 비즈니스 가치를 완성함.

## Ⅳ. 문제점
- 병목 현상: 특정 계층(주로 DB)의 성능 저하가 시스템 전체의 응답 지연으로 전이됨.
- 복잡도 증가: 계층 간 통신 비용 및 관리 포인트 증가로 인해 오버헤드 발생함.

## Ⅴ. 개선방안
- 캐싱 레이어: Web-WAS-DB 사이에 Redis 등 인메모리 캐시를 두어 부하 분산함.
- 수평 확장 (Scale-out): 각 계층을 독립적인 클러스터로 구성하여 동적으로 자원 증설함.

## Ⅵ. 전망
- 마이크로서비스(MSA)로의 분절화가 가속화되며 전통적 N-Tier 개념이 서비스 간 연결망으로 진화됨.
- 프론트엔드가 백엔드 로직 일부를 흡수하는 Edge Side Rendering(ESR) 기술 확산됨.
- 서버리스 환경에서는 계층의 경계가 모호해지며 함수 단위의 조합 아키텍처가 주류를 이룰 것임.
