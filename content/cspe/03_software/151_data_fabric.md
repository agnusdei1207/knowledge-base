## 미리 알고가기

- 데이터 패브릭은 분산된 데이터의 메타데이터·통합·접근·정책을 공통 계층으로 연결하는 아키텍처 접근임
- 활성 메타데이터는 설계 정보뿐 아니라 실행·사용·품질·변경 이벤트를 자동화 판단에 사용하는 메타데이터임
- 지식 그래프는 데이터 자산·업무 용어·소유자·계보·정책의 관계를 그래프로 표현함
- 데이터 가상화는 원본을 이동하지 않고 여러 저장소를 하나의 논리 질의로 제공하는 방식임
- 정책 집행점은 접근·분류·마스킹·보존 규칙을 실제 데이터 경로에 적용하는 구성요소임
- DataOps 자동화는 메타데이터 신호로 파이프라인 배포·품질·장애 대응을 조정함

## 작성 근거(검토용)

- 데이터 패브릭은 활성 메타데이터·지식 그래프·통합·정책 자동화·분산 접근을 핵심으로 선정함
- 비교표는 데이터 메시와 초점·소유권·연결 방식·플랫폼·거버넌스·적합 조건을 대비함
- 순차 처리보다 메타데이터와 실행 계층의 연결이 핵심이므로 Ⅴ절을 생략하고 구조에서 관계를 제시함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 제품 홍보 표현과 모호한 자동화를 제거함

## Ⅰ. 개요

- **정의/개념**: 데이터 패브릭은 분산 저장소의 기술·업무·운영 메타데이터를 연결하고 통합·접근·품질·보안 정책을 자동 집행하는 데이터 관리 아키텍처임
- **배경/필요성**: 클라우드·온프레미스·SaaS에 분산된 데이터를 이동 방식과 관계없이 검색·연결·통제하기 위해 공통 메타데이터와 정책 계층이 필요함

## Ⅱ. 특징

- 카탈로그·계보·사용·품질·실행 메타데이터를 자산 관계 그래프로 연결함
- 배치·스트림·API·가상화 중 데이터 위치와 최신성 요구에 맞는 통합 경로를 선택함
- 분류·소유자·계보 신호를 접근 제어·마스킹·품질 규칙의 집행 조건으로 사용함
- 파이프라인 실행과 사용 패턴을 메타데이터로 다시 수집해 변경 영향과 운영 대상을 찾음
- 메타데이터 표준과 커넥터 범위가 부족하면 자동화가 일부 저장소에만 적용됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 메시 | 데이터 패브릭 |
|:---|:---|:---|
| 중심 문제 | 도메인별 데이터 소유권과 제품 책임 | 분산 데이터의 기술 연결과 정책 집행 |
| 소유 구조 | 도메인 팀이 데이터 제품 소유 | 기존 소유 구조 위에 공통 메타데이터 연결 |
| 연결 단위 | 계약·인터페이스를 갖춘 데이터 제품 | 자산·파이프라인·API·가상화 관계 |
| 플랫폼 역할 | 도메인 개발을 위한 셀프서비스 제공 | 메타데이터 기반 통합·검색·자동화 제공 |
| 거버넌스 | 연합 정책과 도메인별 실행 | 중앙 정책을 분산 집행점에 연결 |
| 적합 조건 | 도메인 변화와 중앙 대기열이 병목 | 저장소·도구 분산과 메타데이터 단절이 병목 |

> 요약: 데이터 메시는 소유권을 도메인 제품으로 분산하고 데이터 패브릭은 메타데이터로 분산 저장소와 정책을 연결함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Connector·Scanner | DB·파일·스트림·SaaS에서 스키마·사용·실행 메타데이터를 수집함 |
| Catalog·Knowledge Graph | 자산·용어·소유자·계보·정책 관계를 저장하고 검색에 제공함 |
| Integration Layer | ETL·ELT·스트림·API·가상화 중 필요한 데이터 연결 방식을 실행함 |
| Policy Engine | 분류와 사용 목적을 기준으로 접근·마스킹·보존 규칙을 판정함 |
| Observability·Automation | 품질·지연·실패·사용 신호로 영향 분석과 운영 작업을 생성함 |
| Access Interface | SQL·API·카탈로그 검색으로 분산 데이터를 소비자에게 제공함 |

```text
DB·Lake·SaaS -> Connector -> Metadata Graph -> Policy·Automation
      |                            |
      +---- Integration·Access ----+-> Consumer
```

> 요약: 메타데이터 그래프가 분산 소스의 통합 경로와 정책 집행점을 연결해 검색·접근·운영 판단을 제공함.

## Ⅵ. 실무 사례

1. 분산 DB 검색은 스키마·용어·소유자를 수집하고 카탈로그 등록률·미소유 자산 수를 확인함
2. 민감 열 제공은 계보 기반 마스킹 정책을 적용하고 미분류 열 수·정책 위반 건수를 확인함

## Ⅶ. 결론

- 데이터 패브릭은 메타데이터 수집 범위·자산 관계 정확성·통합 경로와 정책 집행 자동화 수준으로 판단해야 함
