# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 패브릭을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 분산된 데이터를 메타데이터와 자동화 계층으로 연결하는 데이터 통합 아키텍처
- **왜 필요한가**: 온프레미스 DB, 클라우드 DW, 데이터 레이크, SaaS에 데이터가 흩어지면 사용자는 위치와 권한을 매번 알아야 한다. 데이터 패브릭은 위치 차이를 숨기고 검색, 접근, 품질, 거버넌스를 한 흐름으로 묶는다.
- **핵심 직관**: 여러 창고를 하나의 물류망처럼 연결해, 물건 위치보다 주문 규칙과 추적 정보를 중심으로 움직이는 구조다.

## 깊이 이해
- **배경·문제의식**: 기존 ETL 중심 통합은 시스템이 늘어날수록 파이프라인 수가 N x M으로 증가한다. 데이터 패브릭은 메타데이터, 카탈로그, 계보, 정책 엔진을 공통 계층으로 두어 데이터 위치 변경이 사용자 질의와 분석 흐름에 미치는 영향을 줄인다.
- **작동 원리**: 수집 계층이 기술 메타데이터와 업무 메타데이터를 모으고, 카탈로그가 검색과 의미 연결을 제공한다. 정책 엔진은 RBAC/ABAC와 마스킹을 적용하며, 오케스트레이션 계층은 배치, 스트리밍, 가상화 경로를 선택한다.
- **비유**: 도시 지하철 노선도와 같다. 사용자는 차량기지 위치를 몰라도 환승 규칙과 도착 정보를 보고 목적지까지 이동한다.
- **구체 예시**: 고객 360 분석에서 CRM, 결제 DB, 로그 레이크, 콜센터 SaaS를 직접 복제하지 않고 카탈로그, 계보, 품질 점수 95점 기준, PII 마스킹 정책으로 연결한다.
- **흔한 오해·주의점**: 데이터 패브릭은 단일 제품명이 아니라 아키텍처 패턴이다. 카탈로그만 도입하거나 모든 데이터를 한 저장소로 복제하는 방식은 데이터 패브릭의 일부만 구현한 것이다.

## 연결 개념
- 데이터 카탈로그 - 데이터 자산 검색과 의미 메타데이터 관리
- 데이터 계보 - 데이터 생성, 변환, 사용 경로 추적
- 데이터 거버넌스 - 정책, 권한, 품질 기준의 조직적 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 패브릭 답안은 제품 나열이 아니라 분산 데이터 접근, 메타데이터 자동화, 거버넌스 통제를 하나의 설계 판단으로 묶어야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 패브릭은 분산 데이터 자산을 메타데이터, 카탈로그, 정책, 오케스트레이션으로 연결하는 통합 데이터 아키텍처임.
> 2. **가치**: 데이터 복제 중심 통합을 줄이고, 검색 시간, 권한 검토 시간, 계보 추적 시간을 SLA 지표로 관리함.
> 3. **판단 포인트**: 데이터 가상화, ETL/ELT, 스트리밍 중 어떤 경로를 선택할지는 지연 허용치, 비용, 개인정보 등급으로 결정함.

## Ⅰ. 개요 및 필요성

데이터 패브릭은 분산 데이터 통합 아키텍처임. 기업 데이터는 DW, Lake, SaaS, 운영 DB로 분산되어 검색, 접근권한, 품질 확인 시간이 증가한다. 메타데이터 중심 연결 계층을 두면 데이터 위치 변경에도 분석, AI, 보고 체계를 유지할 수 있다.

---

## Ⅱ. 구조 및 구성요소

```text
Source DB/SaaS/Lake -> Metadata Harvest -> Catalog/Lineage -> Policy Engine -> Access API/BI/AI
                                      +-> Quality Rule
                                      +-> Orchestration
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 메타데이터 수집 | 스키마, 소유자, 품질, 사용 이력 수집 | Apache Atlas, OpenMetadata 연계 |
| 카탈로그/계보 | 검색, 의미 연결, 변환 추적 제공 | 업무 용어와 SQL 계보 동시 관리 |
| 정책 엔진 | 권한, 마스킹, 보존기간 적용 | RBAC/ABAC, PII 태그 기반 |
| 접근 계층 | API, SQL, BI, AI 질의 연결 | 가상화 또는 물리 적재 선택 |

> 요약: 데이터 패브릭은 저장소가 아니라 메타데이터와 정책을 중심으로 데이터 접근 경로를 조정하는 계층형 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산 등록 -> 메타데이터 수집 -> 품질/권한 태깅 -> 접근 경로 선택 -> 사용/계보 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 자산 등록 및 소유자 지정 | owner 100%, SLA 등급 부여 |
| 2 | 스키마, 태그, 사용 로그 수집 | 24시간 이내 카탈로그 반영 |
| 3 | PII, 품질, 보존 규칙 적용 | 마스킹 정책 누락 0건 |
| 4 | 가상화, ETL, 스트리밍 경로 선택 | p95 질의 3초 또는 배치 SLA 준수 |
| 5 | 사용 이력과 계보 자동 기록 | lineage coverage 90% 이상 |

> 요약: 데이터 패브릭은 등록, 수집, 정책 적용, 접근, 기록의 반복 루프로 데이터 활용과 통제를 함께 수행함.

## Ⅳ. 특징

| 구분 | 기존 통합 | 데이터 패브릭 | 판단 포인트 |
|:---|:---|:---|:---|
| 구조 | ETL 파이프라인별 개별 연결 | 메타데이터 공통 계층 | 연결 수 N x M 감소 |
| 접근 | 저장소 위치 인지 필요 | 카탈로그 기반 검색 | 검색 성공률, 재사용률 |
| 통제 | 시스템별 권한 관리 | 정책 엔진 중앙 적용 | PII 마스킹 누락 0건 |
| 한계 | 구현 단순 | 메타데이터 품질 의존 | 태그 정확도 95% 이상 필요 |

> 요약: 데이터 패브릭은 복제보다 연결과 통제를 중시하며, 메타데이터 품질이 도입 성과를 좌우함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 데이터 레이크 단일 적재 | 분산 저장소 연결 | 규제상 원본 이동 제한 시 |
| 처리 | ETL 일괄 복제 | 가상화/ELT/스트리밍 혼합 | p95 지연, 배치 SLA |
| 운영 | 팀별 데이터 관리 | 공통 정책과 카탈로그 | 자산 500개 이상, 소유자 다수 |

> 요약: 데이터 패브릭은 저장소 통합보다 접근 경로와 정책 통합이 필요한 조직에서 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 카탈로그 부정확 | 스키마 변경 미수집 | CDC 메타데이터 수집, 일일 스캔 | stale metadata 1% 이하 |
| 권한 우회 | 원천 시스템 직접 접근 | SSO, RBAC/ABAC, 감사로그 | 비인가 접근 0건 |
| 질의 지연 | 가상화 남용 | 캐시, 물리 적재, 쿼리 푸시다운 | p95 3초 이하 |

> 요약: 주요 리스크는 메타데이터 부정확, 권한 우회, 질의 지연이며 자동 수집과 접근 통제로 낮춘다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 메타데이터 | owner 100%, lineage 90% 이상 | 카탈로그 리포트 |
| 접근 통제 | PII 마스킹 누락 0건 | 정책 테스트, 감사로그 |
| 활용 | 데이터 검색 성공률 80% 이상 | 검색 로그, BI 사용 이력 |

> 요약: 도입 후에는 자산 등록률, 정책 준수율, 사용자 검색 성공률로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 메타데이터 수집: OpenMetadata/Apache Atlas로 DB, Lake, Kafka 스키마를 24시간 주기로 수집하고 owner 필수값 적용
2. 정책 통제: PII 태그, RBAC/ABAC, 동적 마스킹으로 주민번호, 계좌번호 조회를 감사로그에 기록
3. 접근 경로 분리: p95 3초 이하 질의는 캐시/가상화, T+1 보고는 ELT, 1분 이하 이벤트는 Kafka 스트림으로 배치

**결론 (2줄):**
- 기술사 판단: 저장소 수가 많고 규제 데이터가 섞이면 데이터 패브릭, 단일 분석 저장소 중심이면 레이크하우스를 우선 선택함
- 향후 방향: AI 학습 데이터와 기업 검색 품질 확보를 위해 데이터 패브릭은 데이터 계약, 카탈로그, 계보 자동화와 결합됨
