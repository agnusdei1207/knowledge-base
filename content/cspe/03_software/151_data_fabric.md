## 미리 알고가기

- 데이터 패브릭은 분산된 데이터의 메타데이터·통합·접근·정책을 공통 계층으로 연결하는 데이터 관리 아키텍처임
- 활성 메타데이터는 설계 정보뿐 아니라 실행·사용·품질·변경 이벤트를 자동화 판단에 사용하는 메타데이터임
- 지식 그래프는 데이터 자산·업무 용어·소유자·계보·정책의 관계를 그래프로 표현함
- 데이터 가상화는 원본을 이동하지 않고 여러 저장소를 하나의 논리 질의로 제공하는 방식임
- 정책 집행점은 접근·분류·마스킹·보존 규칙을 실제 데이터 경로에 적용하는 구성요소임

## 작성 근거(검토용)

- 데이터 패브릭은 활성 메타데이터·지식 그래프·통합·정책 자동화·분산 접근을 핵심으로 선정함
- 비교표는 데이터 메시와 중심 문제·연결 단위·거버넌스를 대비함
- Ⅴ절은 메타데이터 수집부터 관계 연결·정책 판정·통합 실행·관측 피드백까지의 활성화 절차로 구성함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 제품 홍보 표현과 모호한 자동화를 제거함

## Ⅰ. 개요

- **정의/개념**: 데이터 패브릭은 분산 저장소의 기술·업무·운영 메타데이터를 연결하고 통합·접근·품질·보안 정책을 자동 집행하는 데이터 관리 아키텍처임
- **배경/필요성**: 클라우드·온프레미스·SaaS에 분산된 데이터를 물리 이동·가상 조회 방식과 관계없이 검색·연결·통제하기 위해 공통 메타데이터와 정책 계층이 필요함

### 쉽게 이해하기 (학습용)
- 흩어진 데이터 창고의 위치·관계·정책을 하나의 지도와 자동 연결망으로 관리하는 구조임

## Ⅱ. 특징

- 카탈로그·계보·사용·품질·실행 메타데이터를 자산 관계 그래프로 연결함
- 배치·스트림·API·가상화 중 데이터 위치와 최신성 요구에 맞는 통합 경로를 선택함
- 분류·소유자·계보 신호를 접근 제어·마스킹·품질 규칙의 집행 조건으로 사용함
- 파이프라인 실행과 사용 패턴을 메타데이터로 다시 수집해 변경 영향과 품질·지연 원인을 찾음
- 메타데이터 표준과 커넥터 범위가 부족하면 자동화가 일부 저장소에만 적용됨

### 쉽게 이해하기 (학습용)
- 연결 자동화는 유용하지만 메타데이터가 낡거나 관계가 틀리면 잘못된 접근과 정책 집행이 발생함

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 메시 | 데이터 패브릭 |
|:---|:---|:---|
| 중심 문제 | 도메인별 데이터 소유권과 제품 책임 | 분산 데이터의 기술 연결과 정책 집행 |
| 연결 단위 | 계약·인터페이스를 갖춘 데이터 제품 | 자산·파이프라인·API·가상화 관계 |
| 거버넌스 | 연합 정책과 도메인별 실행 | 중앙 정책을 분산 집행점에 연결 |

> 요약: 데이터 메시는 소유권을 도메인 제품으로 분산하고 데이터 패브릭은 메타데이터로 분산 저장소와 정책을 연결함.

### 쉽게 이해하기 (학습용)
- 데이터 메시는 소유 책임, 패브릭은 분산 자산을 찾고 연결·통제하는 기술망에 초점을 둠

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 커넥터·스캐너 | DB·파일·스트림·SaaS에서 스키마·사용·실행 메타데이터를 수집함 |
| 카탈로그·지식 그래프 | 자산·용어·소유자·계보·정책 관계를 저장하고 검색에 제공함 |
| 통합 계층 | ETL·ELT·스트림·API·가상화 중 필요한 데이터 연결 방식을 실행함 |
| 정책 엔진 | 분류와 사용 목적을 기준으로 접근·마스킹·보존 규칙을 판정함 |
| 관측·자동화 | 품질·지연·실패·사용 신호로 영향 범위와 재실행 대상을 판정함 |
| 접근 인터페이스 | SQL·API·카탈로그 검색으로 분산 데이터를 소비자에게 제공함 |

```text
DB·레이크·SaaS -> 커넥터 -> 메타데이터 그래프 -> 정책·자동화
      |                            |
      +-------- 통합·접근 ---------+-> 소비자
```

> 요약: 메타데이터 그래프가 분산 소스의 통합 경로와 정책 집행점을 연결해 검색·접근·운영 판단을 제공함.

### 쉽게 이해하기 (학습용)
- 자산 스캐너, 관계 지도, 연결 도구, 정책 엔진과 품질·실행 관측 장치로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
[분산 소스 메타데이터 수집] -> [자산·계보·정책 관계 연결]
        -> [접근·통합 경로 판정] -> [정책 집행] -> [품질·사용 신호로 보정]
```

1. DB·파일·스트림·SaaS의 스키마·사용·실행 메타데이터를 수집함
2. 자산·용어·소유자·계보·분류 관계를 지식 그래프에 연결함
3. 소비 요구에 따라 ETL·API·가상화와 접근 정책을 판정함
4. 품질·지연·실패·사용 신호로 관계와 자동화 규칙을 보정함

> 요약: 메타데이터 관계를 실행 가능한 통합·정책 경로로 바꾸고 운영 신호로 지속 보정함.

### 쉽게 이해하기 (학습용)
- 창고 지도를 만든 뒤 목적지와 권한에 맞는 길을 열고 실제 통행 결과로 지도를 고침

## Ⅵ. 실무 사례

1. 분산 DB 검색은 스키마·용어·소유자를 수집하고 카탈로그 등록률·미소유 자산 수를 확인함
2. 민감 데이터 제공은 계보 기반 마스킹 정책을 적용하고 미분류 열 수·정책 위반 건수를 확인함

### 쉽게 이해하기 (학습용)
- 다중 클라우드 자산 검색에서 관계 정확도·정책 적용률·접근 준비 시간을 확인함

## Ⅶ. 결론

- 데이터 패브릭은 메타데이터 수집 범위·자산 관계 정확성·통합 경로·정책 집행 자동화 수준을 기준으로 도입해야 함
- 제품의 자동화 주장보다 메타데이터 최신성·관계 신뢰도·정책 오판과 수동 보정 비용을 실측해야 함

### 쉽게 이해하기 (학습용)
- 자동 지도라는 이름보다 길이 최신이고 잘못 안내할 때 바로 고칠 수 있는지가 중요함
