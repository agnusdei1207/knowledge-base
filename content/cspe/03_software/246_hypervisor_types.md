## Ⅰ. 개요
- 정의: 호스트 컴퓨터에서 다수의 운영체제를 동시에 실행하기 위한 논리적 계층임
- 배경: 서버 통합을 통한 비용 절감 및 독립된 테스트 환경 구축 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| Type 1 | 베어메탈, 고성능 | 매우높음 |
| Type 2 | 호스트형, 범용성 | 높음 |

- 구성요소 표

| Type 1 (Bare-metal) | 하드웨어 바로 위에서 실행되는 방식 | 건물 1층의 직접 입주 |
| Type 2 (Hosted) | 기존 운영체제 안에서 앱처럼 실행되는 방식 | 셋방살이 |
| VMM | 가상 머신 관리자 (Virtual Machine Monitor) | 아파트 관리인 |

> 요약: 실행 위치에 따라 성능과 용도가 명확히 구분되는 가상화 기술임

## Ⅲ. 비교 분석
- 4단계 설명 (차이점)
1. 실행구조: Type 1은 직접 제어하고, Type 2는 호스트 OS의 도움을 받음
2. 성능효율: Type 1은 오버헤드가 적어 고성능, Type 2는 OS 간섭으로 비교적 낮음
3. 안정성: Type 1은 호스트 OS 장애 우려가 없어 안정적, Type 2는 호스트 종속적임
4. 용도: Type 1은 엔터프라이즈 서버/클라우드, Type 2는 개인 개발/테스트용임

> 요약: 고성능/안정성은 Type 1, 간편한 설치/범용성은 Type 2가 유리함

## Ⅳ. 문제점
- 하이퍼바이저 자체가 보안 취약점이 될 경우 하위의 모든 VM이 위험에 노출됨
- 특정 하이퍼바이저 벤더(VMware 등)에 대한 종속성(Lock-in) 문제가 심각함

## Ⅴ. 개선방안
- (단기) 하이퍼바이저 보안 패치를 주기적으로 수행하고 격리 기술 강화함
- (중기) 오픈소스 기반 KVM(Kernel-based VM) 도입으로 비용 및 종속성 탈피함
- (장기) 컨테이너와 VM의 장점을 결합한 Katacontainers 등 융합 기술 도입함

## Ⅵ. 전망
- 보안이 강화된 Micro-hypervisor 기술이 자동차, 의료 등 임베디드 분야 확산됨
- 하드웨어 보조 가상화(Intel VT-x 등) 기술의 발전으로 성능 격차가 소멸될 것임
