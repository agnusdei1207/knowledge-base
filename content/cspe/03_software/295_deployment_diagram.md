## Ⅰ. 개요
- 정의: 소프트웨어 컴포넌트가 하드웨어 노드에 어떻게 배치되고 통신하는지 표현함
- 배경: 분산 시스템 아키텍처 가시화 및 인프라 자원 할당 계획 수립 필요
- 출제 의도: 시스템의 물리적 토폴로지(Topology) 및 네트워크 구성 설계 역량 평가

## Ⅱ. 구성요소
- ASCII 구조도
  +----------+         +----------+
  |  Node A  |--[TCP]--|  Node B  |
  | (Server) |         | (DB Ser) |
  +----------+         +----------+
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 노드(Node) | 실행 환경을 제공하는 물리적/가상 하드웨어 | 본체/서버 |
| 아티팩트(Artifact) | 노드에 배치되는 실제 실행 파일(JAR, WAR) | 설치 프로그램 |
| 통신 경로 | 노드 간 연결 매체 및 프로토콜(HTTP, JDBC) | 랜선/통신망 |
> 요약: 하드웨어 노드와 그 위에 배치되는 실행 자산 및 네트워크 경로를 기술함

## Ⅲ. 절차
- ASCII 흐름도
  Node ID -> Network Def -> Artifact Mapping -> Detail
- 4단계 설명
1. Node ID: 서버, 클라이언트, 스토리지 등 물리적 실행 환경 식별함
2. Network Def: 노드 간의 물리적 연결 방식 및 통신 프로토콜 정의함
3. Artifact Mapping: 각 노드에 배치될 소프트웨어 구성 요소 할당함
4. Detail: 각 노드의 성능 사양(CPU, RAM) 및 다중화 구성 명세화함
> 요약: 인프라 노드를 도출하고 소프트웨어를 매핑하여 실제 운영 환경을 설계함

## Ⅳ. 문제점
- 오토스케일링과 동적 재배치가 발생하면 정적 다이어그램의 노드 수·위치·연결 정보가 실제 환경과 달라짐

## Ⅴ. 개선방안
- IaC 정의와 실행 환경의 토폴로지 정보를 연계하여 배치 다이어그램을 갱신함

## Ⅵ. 전망
- 엣지 컴퓨팅 및 멀티 클라우드 환경을 반영한 분산 배치 최적화 모델 부각
- CSF: 가용성 확보를 위한 이중화(HA)와 부하 분산(LB) 지점의 명확한 설계가 핵심임
