## Ⅰ. 개요
- 정의: 객체 간의 메시지 교환과 상호작용 순서를 시간 흐름에 따라 시각화하는 기법임
- 배경: 정적 모델에서 파악하기 어려운 런타임 동작 및 비즈니스 로직 검증 필요
- 출제 의도: 객체 간 협력 구조 및 메시지 흐름 설계 역량 확인

## Ⅱ. 구성요소
- ASCII 구조도
  Obj A      Obj B
    |---msg--->|
    |          |--self_call--+
    |<--return-|             |
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 생명선(Lifeline) | 객체의 존재 기간을 나타내는 수직선 | 등장인물 수명 |
| 메시지(Message) | 객체 간의 데이터 전달 및 메소드 호출 | 대화/전화 |
| 활성창(Activation)| 객체가 연산을 수행 중인 상태 표시 | 대화 시간 |
> 요약: 객체들의 생존 기간 내 발생하는 상호작용을 메시지 순서로 표현함

## Ⅲ. 절차
- ASCII 흐름도
  Context ID -> Object ID -> Message Flow -> Refinement
- 4단계 설명
1. Context ID: 모델링할 유스케이스나 시나리오의 범위를 설정함
2. Object ID: 참여하는 주요 객체(Actor, Controller, Entity) 식별함
3. Message Flow: 객체 간 호출 순서 및 리턴 값을 시간 순으로 배치함
4. Refinement: 반복(Loop), 선택(Alt) 등 제어 구조를 적용하여 상세화함
> 요약: 시나리오 선정 후 관련 객체들 간의 메시지 흐름과 제어 로직을 작성함

## Ⅳ. 문제점
- 모든 메서드 호출까지 모델링하면 코드 변경마다 메시지 흐름을 수정해야 해 모델과 구현이 쉽게 불일치함

## Ⅴ. 개선방안
- 업무 시나리오와 서비스 경계의 핵심 메시지만 모델링하고 트레이싱·역공학 결과로 변경 여부를 확인함

## Ⅵ. 전망
- 분산 마이크로서비스 환경의 트레이싱 로그 기반 동적 시퀀스 자동 생성 기술 부각
- CSF: 객체의 책임 할당 원칙(GRASP)에 기반한 효율적인 메시지 설계가 성능과 직결됨
