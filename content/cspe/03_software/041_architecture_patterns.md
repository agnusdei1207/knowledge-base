## 미리 알고가기

- MVC(Model-View-Controller): 사용자 인터페이스(View), 비즈니스 로직(Model), 흐름 제어(Controller)로 역할을 구분하는 아키텍처 패턴임
- MSA(Microservice Architecture): 단일 애플리케이션을 여러 개의 독립적인 마이크로서비스들의 집합으로 설계하는 서비스 지향 아키텍처임
- EDA(Event-Driven Architecture): 시스템 내외의 상태 변화(이벤트)를 감지하고 전파하여 비동기식으로 처리하는 구조임
- 느슨한 결합(Loose Coupling): 컴포넌트 간 상호 의존성을 최소화하여 변경의 영향도를 줄이는 설계 원칙임
- 비동기 통신(Asynchronous Communication): 요청을 보낸 뒤 응답을 대기하지 않고 다른 작업을 처리할 수 있는 통신 방식임

## 작성 근거(검토용)

- 아키텍처 패턴은 분리 기준, 변경·배포 단위, 구조상 한계를 핵심 비교축으로 선정하여 기술 특성의 비교 분석 가치를 높임
- MVC·MSA·이벤트드리븐 구조는 화면 책임, 서비스 경계, 이벤트 계약이라는 서로 다른 분리 대상을 기준으로 전개하여 일관성을 확보함
- 문장별 5회 전수 검수 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정했음을 밝힘

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 아키텍처 패턴은 반복되는 설계 문제의 책임·경계·상호작용을 재사용 가능한 구조로 정리한 해법임
- **배경/필요성**: UI 변경, 서비스 독립 배포, 비동기 통합 요구에 따라 분리 대상이 달라지므로 구조 선택 기준이 필요함

### 쉽게 이해하기 (학습용)
- 집을 지을 때 거실과 방의 목적에 따라 원룸형(MVC), 단독 단지형(MSA), 무전기 연락망(이벤트드리븐) 등 설계 도면을 미리 골라 쓰는 것과 같습니다.

## Ⅱ. 특징

- MVC는 표현 계층과 처리 계층을 나눠 화면 변경 부담을 줄임
- MSA는 서비스별 배포와 확장을 가능하게 하지만 운영 복잡도를 키움
- 이벤트드리븐 구조는 생산자와 소비자가 이벤트 계약을 통해 비동기로 통신함
- 하나의 시스템에서도 계층별로 서로 다른 패턴을 함께 사용할 수 있음

### 쉽게 이해하기 (학습용)
- 하나의 큰 빌딩 안에서 전체 운영 시스템은 각 층별로 나누어(MSA) 관리하면서, 개별 매장 내부는 카운터와 대기실로 구분(MVC)하여 효율성을 극대화합니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | MVC | MSA | 이벤트드리븐 |
|:---|:---|:---|:---|
| 주된 분리 기준 | 화면, 입력 처리, 비즈니스 로직을 계층으로 나눔 | 비즈니스 기능을 서비스 단위로 나눔 | 상태 변화를 이벤트와 소비자 관계로 나눔 |
| 변경·배포 단위 | Model·View·Controller 책임별 변경 | 서비스별 독립 빌드·배포·확장 | 생산자·소비자를 독립 변경하고 이벤트 계약으로 연결 |
| 주요 설계 리스크 | 서비스 독립 배포를 지원하지 않음 | 데이터 분산·네트워크 장애·운영 자동화 부담 | 추적·재처리·이벤트 일관성 관리 부담 |

### 쉽게 이해하기 (학습용)
- 거대한 원룸(MVC)은 방 교체가 어렵지만 관리하기 쉽고, 독립된 아파트(MSA)는 방마다 수리하기 좋으나 공용 시설 관리가 복잡하며, 무전기 연락망(이벤트드리븐)은 필요할 때만 신호를 주고받아 유연합니다.

## Ⅳ. 설계 요소 및 구조

```text
+-----------------------+     +-----------------------+     +-----------------------+
|          MVC          |     |          MSA          |     |      Event-Driven     |
| [Controller] -> [Model] |     |     [API Gateway]     |     |   [Event Producer]    |
|       |                 |     |      /         \      |     |          |            |
|       v                 |     |     v           v     |     |          v            |
|    [View]               |     | [Service A] [Service B] |     |    [Event Broker]     |
|                         |     |                       |     |          |            |
|                         |     |                       |     |          v            |
|                         |     |                       |     |   [Event Consumer]    |
+-----------------------+     +-----------------------+     +-----------------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 표현 책임 분리 | MVC의 모델·뷰·컨트롤러가 데이터, 화면, 입력 제어 책임을 나눔 |
| 서비스 경계 | MSA가 비즈니스 기능을 독립 배포·확장·장애 격리 단위로 나눔 |
| 이벤트 브로커 | 생산자 이벤트를 소비자에게 전달해 직접 호출 의존성을 줄임 |
| 계약 인터페이스 | 계층·서비스·이벤트 사이의 입력·출력 규약으로 변경 범위를 제한함 |

### 쉽게 이해하기 (학습용)
- 역할을 구분하는 직원들(MVC), 가게의 부서(MSA), 배달을 대행해주는 택배 기사(브로커), 서로 약속한 배송지 양식(계약)이 맞물려 돌아가는 정적인 뼈대입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[MVC 동작 원리]
사용자 입력 -> Controller 처리 -> Model 데이터 갱신 -> View에 반영 -> 응답

[MSA 호출 원리]
사용자 요청 -> API Gateway 라우팅 -> 개별 서비스 로직 수행 -> 응답 병합 -> 응답

[Event-Driven 비동기 흐름]
이벤트 발생 -> Producer가 Broker로 송신 -> Consumer가 Broker로부터 수신 -> 비동기 처리 완료
```

1. **MVC 요청 제어**: Controller가 사용자의 입력을 받아 Model을 제어하고 변경 정보를 View에 동기화함
2. **MSA 게이트웨이 분기**: 단일 진입점이 요청을 해석하여 도메인별 마이크로서비스로 라우팅 및 처리함
3. **EDA 이벤트 브로커 중계**: Producer가 발행한 이벤트를 Broker가 큐잉하고 Consumer가 이를 비동기 수신함

### 쉽게 이해하기 (학습용)
- 손님이 주문하면 주방장이 요리하고 웨이터가 접시에 담아 내어주거나, 입구의 안내원이 각 부서로 안내하거나, 주문 신호가 들어왔을 때 알람을 울려 각자 일을 시작하는 세 가지 흐름입니다.

## Ⅵ. 실무 사례

1. 업무 포털은 MVC의 업무 규칙을 모델 계층에 배치하고 컨트롤러 복잡도·단위 테스트 커버리지를 확인함
2. 주문 이벤트 플랫폼은 이벤트 스키마 버전을 관리하고 계약 위반 건수·재처리 성공률을 확인함

### 쉽게 이해하기 (학습용)
- 기업용 결제 시스템 구축 시 화면 영역은 MVC 패턴을 유지하고, 주문서와 배송 시스템은 독립된 MSA로 쪼개며, 배송 상태 변경 시 알림 큐를 이용해 고객에게 비동기 알림을 보냅니다.

## Ⅶ. 결론

- 아키텍처 패턴은 비즈니스 요구사항과 도메인 성격에 따라 서비스 책임과 변경 영향의 범위를 분리하는 핵심 구조 설계 기법임
- 조직의 규모와 운영 역량을 고려하여 단일 구조에 매몰되지 않고 적재적소에 하이브리드 패턴을 융합하는 실무적인 아키텍처 의사결정이 필요함

### 쉽게 이해하기 (학습용)
- 상황에 따라 아파트 형태나 일반 주택 형태를 골라 지어야 하듯이, 전체 구조의 가용성과 유지보수 편의를 고려하여 최선의 조합을 고르는 것이 핵심입니다.
