## 미리 알고가기

- 아키텍처 패턴은 반복되는 설계 문제에 대한 구조적 해법임
- MVC는 계층 분리, MSA는 서비스 분리, 이벤트드리븐은 비동기 결합 완화가 핵심임
- 선택 기준은 기술 유행보다 변경 방향과 운영 복잡도임

## Ⅰ. 개요

- **정의/개념**: 소프트웨어 아키텍처 패턴은 시스템을 어떤 구성요소와 관계로 나눌지에 대한 반복 가능한 구조 해법이며, 대표적으로 MVC와 MSA와 이벤트드리븐 구조가 널리 사용됨
- **배경/필요성**: 시스템 규모와 변경 속도와 배포 단위와 통합 방식이 달라지면서, 단일 설계 방식으로는 모든 요구를 만족하기 어려워 패턴별 선택 기준이 필요해짐

## Ⅱ. 특징

- MVC는 프레젠테이션 관심사를 분리해 UI 변경에 유리함
- MSA는 서비스 단위 배포와 확장을 가능하게 하지만 운영 복잡도가 큼
- 이벤트드리븐은 서비스 결합도를 낮추고 비동기 확장성을 높임
- 같은 시스템 안에서도 계층별로 서로 다른 패턴을 함께 사용할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | MVC | MSA | 이벤트드리븐 |
|:---|:---|:---|:---|
| 핵심 분리 축 | UI와 비즈니스 로직 | 도메인 서비스 단위 | 이벤트와 소비자 단위 |
| 장점 | 구조 명확, UI 변경 대응 | 배포 독립성, 확장성 | 느슨한 결합, 비동기 확장 |
| 한계 | 대규모 분산 문제 해결 한계 | 운영 복잡도와 데이터 분산 | 추적과 일관성 관리 어려움 |
| 적합 환경 | 웹 애플리케이션 UI 계층 | 복합 비즈니스 서비스 | 실시간 통합과 비동기 처리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Presentation Separation | MVC에서 View와 Controller와 Model을 나눠 사용자 인터페이스 변경 부담을 낮춤 |
| Service Boundary | MSA에서 기능을 독립 서비스로 잘라 배포와 확장과 장애 격리 단위를 형성함 |
| Event Bus or Broker | 이벤트드리븐 구조에서 생산자와 소비자 사이 결합을 낮추는 핵심 연결 계층임 |
| Contract Interface | 각 패턴에서 계층이나 서비스나 이벤트 간 상호작용 규약을 정의해 변경 영향을 제한함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요구 특성 분석  | --> | 분리 축 선택   | --> | 상호작용 규약 정의 | --> | 운영 검증      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요구 특성 분석**: UI 중심인지 서비스 분리 중심인지 비동기 통합 중심인지 파악함
2. **분리 축 선택**: 적합한 패턴 또는 혼합 구조를 결정함
3. **상호작용 규약 정의**: API와 이벤트와 계층 경계를 명확히 함
4. **운영 검증**: 배포 독립성과 추적성과 장애 범위를 검증함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 시스템 특성과 무관하게 유행 패턴을 도입하면 구조만 복잡해지고 유지비가 급증할 수 있음
   - 해결방안: 변경 방향과 배포 단위를 기준으로 선택하고 architecture fit score와 operational overhead로 검증함
2. 문제: MSA와 이벤트드리븐을 함께 도입하면서 경계와 계약이 약하면 서비스 간 혼선이 커질 수 있음
   - 해결방안: 계약 우선 설계와 schema governance를 적용하고 contract break rate와 integration defect count로 검증함
3. 문제: MVC 구조도 계층 경계가 무너지면 컨트롤러 비대화와 테스트 어려움이 누적될 수 있음
   - 해결방안: 계층 책임 규칙과 리뷰를 운영하고 controller complexity와 unit test coverage로 검증함

## Ⅶ. 적용 사례

- 웹 포털 UI 설계에서는 MVC를 적용하고, controller complexity와 unit test coverage로 결과를 확인함
- 대형 주문 서비스에서는 MSA를 채택하고, deployment independence rate와 operational overhead로 결과를 확인함
- 실시간 이벤트 처리 플랫폼에서는 이벤트드리븐 구조를 사용하고, contract break rate와 end-to-end latency로 결과를 확인함

## Ⅷ. 결론

아키텍처 패턴 선택은 이름을 고르는 일이 아니라 시스템이 가장 자주 변하는 축을 어떤 구조 경계로 받아낼지 정하는 설계 판단임.
