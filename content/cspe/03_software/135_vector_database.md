## Ⅰ. 개요
- **정의**: 고차원 벡터 임베딩을 저장하고 유사도 기반 근사 최근접 탐색(ANN)을 수행하는 DB
- **배경/필요성**: LLM·이미지 검색 등 비정형 데이터의 의미 기반 유사도 검색 수요가 급증함
- **비유**: 도서관에서 제목이 아닌 내용 유사도로 관련 도서를 찾아주는 사서와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ANN 인덱스 원리와 AI 연계 | HNSW·IVF 인덱스 구조와 recall-latency 트레이드오프 | 전문검색(Full-text)과 벡터 검색의 차이 구분 필요 |

> 요약: 임베딩 벡터의 ANN 검색에 특화된 유사도 중심 DB임

## Ⅱ. 구성요소
```text
Raw Data --> Embedding Model --> Vector Store --> ANN Index --> Query Engine
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Embedding Model | 텍스트·이미지를 고차원 벡터로 변환하는 모델 | 내용 요약 번역기 |
| Vector Store | 벡터와 메타데이터를 함께 저장하는 스토리지 | 좌표 저장 창고 |
| ANN Index | HNSW·IVF 등 근사 최근접 탐색용 인덱스 구조 | 공간 분할 색인표 |
| Query Engine | 쿼리 벡터와 저장 벡터 간 유사도 계산·필터링 수행 | 유사 문서 검색기 |

> 요약: 임베딩-저장-ANN 인덱스-유사도 조회의 파이프라인 구조임

## Ⅲ. 절차
```text
데이터 임베딩 --> 벡터 적재 --> ANN 인덱스 구축 --> 유사도 검색
```
- 1단계: 원본 데이터를 임베딩 모델로 고차원 벡터로 변환
- 2단계: 벡터와 원본 메타데이터를 벡터 스토어에 적재
- 3단계: HNSW·IVF 등 ANN 인덱스를 구축하여 탐색 공간 최적화
- 4단계: 쿼리 벡터로 Top-K 유사 벡터를 검색하고 메타데이터 반환

> 요약: 임베딩-적재-인덱싱-검색 4단계로 유사도 기반 조회를 수행함

## Ⅳ. 문제점
- Recall-Latency 트레이드오프: ANN 근사치 정확도를 높이면 검색 지연이 증가함
- 임베딩 모델 의존성: 모델 변경 시 전체 벡터 재생성이 필요하여 운영 비용 증가함
- 복합 필터 성능: 메타데이터 필터와 벡터 검색 결합 시 인덱스 효율이 저하됨

> 요약: 정확도-속도 균형, 모델 종속, 복합 필터 성능이 주요 과제임

## Ⅴ. 개선방안
1. 단기: Recall-Latency → 인덱스 파라미터(`ef`, `nprobe`) 튜닝으로 최적점 탐색
2. 중기: 임베딩 의존성 → 모델 버전별 네임스페이스 분리 및 점진적 재인덱싱
3. 장기: 복합 필터 → 벡터-메타데이터 하이브리드 인덱스 구조 도입

> 요약: 파라미터 튜닝, 네임스페이스 분리, 하이브리드 인덱스로 단계적 개선함

## Ⅵ. 전망
- 발전 방향: RAG 파이프라인 핵심 인프라로서 LLM 생태계와 긴밀히 통합되는 추세임
- 기술사적 판단: AI 서비스 확산으로 벡터 DB 설계·운영 역량이 필수 요건이 됨
- 기술사 제언: 임베딩 차원·데이터 규모에 따라 ANN 알고리즘을 선정할 것을 제언함
