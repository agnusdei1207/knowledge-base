## 미리 알고가기

- 사용자 네임스페이스는 컨테이너 UID·GID를 호스트의 다른 UID·GID 범위에 대응시킴
- 하위 UID·GID는 일반 사용자에게 할당한 호스트 계정 범위이며 다중 ID 매핑에 사용함
- Rootless 모드는 데몬과 컨테이너를 모두 일반 사용자 권한으로 실행함
- Rootful 모드는 컨테이너 데몬을 호스트 루트 권한으로 실행함
- `userns-remap`은 컨테이너 ID를 바꾸지만 시스템 데몬 자체는 루트 권한으로 실행함
- cgroup·네트워크·장치 기능은 호스트 커널과 Rootless 런타임의 지원 범위를 확인해야 함

## 작성 근거(검토용)

- Rootless 컨테이너는 데몬 권한, 사용자 네임스페이스, UID·GID 매핑, 기능 제약을 핵심 축으로 설명함
- 비교표는 Rootful·`userns-remap`·Rootless의 호스트 권한과 격리 경계를 같은 수준에서 대비함
- 공용 CI와 개발 서버에서 호스트 권한 노출과 런타임 호환성을 검증함

## Ⅰ. 개요

- **정의/개념**: Rootless 컨테이너는 데몬·런타임·컨테이너 프로세스를 일반 사용자 권한으로 실행하고 컨테이너 ID를 호스트 하위 UID·GID에 매핑하는 실행 방식임
- **배경/필요성**: 컨테이너 런타임이 침해돼도 호스트 루트 권한으로 이어지는 범위를 제한하기 위해 비특권 실행 경계가 필요함

## Ⅱ. 특징

- 데몬과 컨테이너가 사용자 네임스페이스 안에서 실행돼 호스트 루트 권한을 보유하지 않음
- 컨테이너의 루트 UID는 호스트에서 일반 사용자 또는 하위 UID 범위로 변환됨
- 사용자별 소켓·저장소·서비스를 사용해 시스템 데몬과 실행 환경을 분리함
- 특권 포트·장치 접근·cgroup 위임은 커널과 호스트 설정에 따라 제한될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Rootful | `userns-remap` | Rootless |
|:---|:---|:---|:---|
| 데몬 권한 | 호스트 루트로 실행 | 호스트 루트로 실행 | 일반 사용자로 실행 |
| 컨테이너 ID | 컨테이너와 호스트에서 같은 UID·GID로 해석 | 하위 UID·GID로 매핑 | 사용자 네임스페이스의 하위 UID·GID로 매핑 |
| 권한 경계 | 데몬 침해 시 호스트 루트 노출 가능 | 컨테이너 UID·GID만 호스트 하위 범위로 변환 | 데몬과 컨테이너의 호스트 권한을 함께 제한 |
| 시스템 기능 | 호스트가 허용한 장치·네트워크·cgroup 기능 사용 | 데몬 기능을 유지하며 ID만 변환 | 커널 위임과 비특권 기능 지원이 필요 |
| 운영 단위 | 시스템 데몬을 공동 사용 | 시스템 데몬을 공동 사용 | 사용자별 데몬·소켓·저장소 사용 |
| 적합 조건 | 특권 장치와 호스트 제어가 필요 | 데몬 유지와 ID 격리가 필요 | 일반 사용자 단위 실행과 권한 축소가 필요 |

> 요약: Rootless는 데몬과 컨테이너를 모두 일반 사용자로 실행해 호스트 권한 노출 범위를 줄임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 일반 사용자 계정 | 데몬과 컨테이너 프로세스의 호스트 권한 주체가 됨 |
| 사용자 네임스페이스 | 컨테이너 UID·GID와 호스트 하위 UID·GID를 분리함 |
| Rootless 런타임 | 사용자별 소켓·저장소를 관리하고 컨테이너 실행을 제어함 |
| 비특권 네트워크 | 사용자 권한에서 포트 전달과 컨테이너 통신을 제공함 |
| cgroup 위임 | 일반 사용자에게 허용된 범위에서 CPU·메모리 자원을 제어함 |

```text
일반 사용자 -> Rootless 데몬 -> 사용자 네임스페이스 -> 컨테이너 프로세스
                       |                    |
                       +-> 비특권 네트워크  +-> 하위 UID·GID 매핑
```

> 요약: 사용자 네임스페이스와 하위 UID·GID 매핑이 컨테이너 권한을 호스트 일반 사용자 범위로 제한함.

## Ⅵ. 실무 사례

1. 공용 CI 실행기는 Rootless 컨테이너로 빌드를 격리하고 UID 매핑 오류·권한 거부 건수를 확인함
2. 개발 서버는 사용자별 Rootless 데몬을 운영하고 소켓 접근·컨테이너 기동 실패율을 확인함

## Ⅶ. 결론

- Rootless 컨테이너는 호스트 권한 노출을 줄여야 하며 네트워크·cgroup·장치 호환성을 확인할 때 적용함
