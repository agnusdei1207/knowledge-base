## 미리 알고가기

- ADR은 중요한 아키텍처 결정을 짧고 구조화된 문서로 남기는 방식임
- 결정 자체보다 배경과 대안과 결과를 함께 기록해야 의미가 있음
- 후속 유지보수와 온보딩과 재검토 비용을 줄이는 데 유용하다

## Ⅰ. 개요

- **정의/개념**: 아키텍처 결정 기록 ADR은 특정 설계 선택에 대해 문제 맥락과 고려한 대안과 최종 결정과 예상 결과를 짧고 구조화된 형식으로 남기는 문서 방식임
- **배경/필요성**: 시간이 지나면 왜 그 기술을 선택했는지 기억이 사라져 같은 논의를 반복하거나 잘못된 변경을 할 수 있으므로, 중요한 설계 판단을 추적 가능하게 남길 필요가 있음

## Ⅱ. 특징

- 짧고 구조화된 형식으로 설계 의도를 남긴다
- 코드와 문서와 운영 판단을 연결하는 설명 책임을 높인다
- 문서가 오래 갱신되지 않으면 오히려 잘못된 기준이 될 수 있다
- 모든 사소한 선택이 아니라 중요한 장기 영향 결정에 집중해야 한다

## Ⅲ. 종류 및 비교

| 판단 기준 | 구두/암묵적 결정 | ADR |
|:---|:---|:---|
| 추적성 | 낮음 | 높음 |
| 장점 | 빠른 결정 | 재검토와 온보딩 용이 |
| 한계 | 맥락 상실 쉬움 | 기록과 관리 비용 필요 |
| 적합 환경 | 단기 임시 결정 | 장기 영향 설계 결정 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Context | 어떤 문제와 제약 때문에 결정을 하게 되었는지 배경을 설명한다 |
| Decision | 채택한 대안을 명확히 적어 이후 해석 차이를 줄인다 |
| Alternatives Considered | 검토했지만 선택하지 않은 대안을 남겨 향후 재평가 근거를 만든다 |
| Consequences | 비용과 위험과 후속 영향까지 기록해 의사결정 책임을 분명히 한다 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 결정 후보 식별  | --> | 맥락/대안 정리 | --> | 결정 기록      | --> | 재검토/갱신    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **결정 후보 식별**: 장기 영향이 큰 설계 선택을 찾음
2. **맥락과 대안 정리**: 제약과 후보와 판단 기준을 정리함
3. **결정 기록**: 채택안과 이유와 결과를 ADR로 남김
4. **재검토 및 갱신**: 환경 변화 시 ADR을 참고하거나 갱신함

## Ⅵ. 문제점 및 해결 방안

1. 문제: ADR을 형식적으로만 작성하면 실제 설계 맥락과 트레이드오프가 남지 않아 가치가 떨어질 수 있음
   - 해결방안: 맥락과 대안과 결과를 필수로 기록하고 adr completeness score와 reread usefulness score로 검증함
2. 문제: 시스템이 바뀌어도 ADR이 갱신되지 않으면 오래된 판단이 현재 설계를 오도할 수 있음
   - 해결방안: 정기 리뷰와 상태 표시를 운영하고 stale adr ratio와 architecture drift count로 검증함
3. 문제: 너무 많은 사소한 결정까지 ADR로 남기면 관리 비용만 늘고 핵심 기록이 묻힐 수 있음
   - 해결방안: 중요도 기준을 두고 adr signal-to-noise ratio와 authoring overhead로 검증함

## Ⅶ. 적용 사례

- 플랫폼 기술 선택 회의에서는 ADR을 작성하고 확인 지표는 adr completeness score와 reread usefulness score임
- 레거시 개편 프로젝트에서는 과거 결정을 재검토하고 확인 지표는 stale adr ratio와 architecture drift count임
- 아키텍처 리뷰 조직에서는 기록 중요도 기준을 운영하고 확인 지표는 adr signal-to-noise ratio와 authoring overhead임

## Ⅷ. 결론

ADR의 본질은 문서를 더 만드는 데 있지 않고 중요한 설계 판단이 왜 내려졌는지 나중에도 재현 가능하게 남겨 변경 비용을 줄이는 데 있음.
