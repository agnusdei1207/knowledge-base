## 미리 알고가기

- 문서형은 한 건의 데이터를 JSON 같은 문서 단위로 저장하는 방식임
- 키값형은 고유 키 하나로 값을 조회하는 방식임
- 컬럼형은 넓은 테이블을 분산 저장해 대량 쓰기와 집계에 맞춘 방식임
- 그래프형은 정점과 간선으로 관계를 저장해 연결 탐색에 맞춘 방식임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- NoSQL은 데이터 모델·조회 방식·분산 기준을 핵심 축으로 설명함
- 비교표는 문서형·키값형·컬럼형·그래프형의 저장 단위와 적합 조회를 대비함
- 서비스 저장소는 p95 조회 지연·파티션 크기 편차로 검증함

## Ⅰ. 개요

- **정의/개념**: NoSQL은 문서·키값·컬럼·그래프 모델로 데이터를 저장해 각 모델에 맞는 조회와 분산 처리를 지원하는 비관계형 데이터베이스임
- **배경/필요성**: 가변 속성·대량 단건 조회·분산 쓰기·관계 탐색을 지원하기 위해 데이터 형태와 접근 패턴에 맞는 저장 모델이 필요함

## Ⅱ. 특징

- 저장 모델이 달라지면 조회 방식과 확장 방식도 함께 달라짐
- 문서·키값 모델은 레코드별 속성 구성을 다르게 저장할 수 있지만 애플리케이션에서 스키마 검증과 버전 호환을 관리해야 함
- 조인과 강한 트랜잭션 기능은 약한 경우가 많아 업무 경계를 분명히 나눠야 함
- 유형을 잘못 고르면 응용 프로그램의 우회 로직이 늘어남

## Ⅲ. 종류 및 비교

| 판단 기준 | 문서형 | 키값형 | 컬럼형 | 그래프형 |
|:---|:---|:---|:---|:---|
| 저장 단위 | 문서 | 키와 값 | 행 키와 컬럼 묶음 | 정점과 간선 |
| 적합 조회 | 객체 단위 조회 | 단건 조회 | 대량 쓰기와 파티션 내 범위 조회 | 관계 추적과 경로 탐색 |
| 접근 구조 | 문서 필드·중첩 객체 조회 | 키 기반 값 조회 | 파티션·행·컬럼 기반 조회 | 노드·간선·속성 기반 탐색 |
| 주의점 | 중첩 데이터가 늘면 문서 크기와 갱신량이 증가함 | 키 외 조건 검색이 제한됨 | 파티션 키가 다르면 조회가 여러 노드로 확산됨 | 전체 집계는 관계 탐색 모델과 맞지 않을 수 있음 |

> 요약: 문서형은 객체, 키값형은 단건, 컬럼형은 분산 쓰기·범위 조회, 그래프형은 관계 탐색에 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 모델 | 문서, 키와 값, 컬럼 묶음, 그래프처럼 저장 단위를 정함 |
| 파티션 기준 | 어떤 키로 데이터를 나눌지 정해 확장성과 쏠림을 좌우함 |
| 복제 정책 | 읽기 성능과 장애 복구 수준을 결정함 |
| 질의 방식 | 키 조회·문서 조회·파티션 내 범위 조회·관계 탐색처럼 접근 방식을 정함 |

> 요약: 데이터 모델과 파티션·복제 정책이 저장 구조를 만들고 질의 방식이 데이터 접근 경로를 결정함.

## Ⅵ. 실무 사례

1. 상품 카탈로그는 문서형 DB에 가변 속성을 저장하고 문서 크기·p95 조회 지연을 확인함
2. 이상 거래 탐지는 그래프 DB로 다단계 관계를 탐색하고 탐색 깊이·질의 시간을 확인함

## Ⅶ. 결론

- NoSQL은 데이터 형태·조회 패턴·분산 요구에 맞춰 문서·키값·컬럼·그래프 모델을 선택함
