## 미리 알고가기

- NoSQL은 관계형 모델 외의 다양한 데이터 모델을 사용하는 분산 데이터 저장 계열임
- 문서형과 키값형과 컬럼형과 그래프형은 데이터 구조와 질의 방식이 다름
- 확장성과 유연성을 얻는 대신 일관성과 조인 기능은 설계로 보완해야 함

## Ⅰ. 개요

- **정의/개념**: NoSQL 유형은 대규모 분산 환경에서 유연한 데이터 모델과 수평 확장성을 확보하기 위해 문서형과 키값형과 컬럼형과 그래프형처럼 데이터 접근 패턴에 맞춰 구조를 달리한 비관계형 데이터 저장 방식임
- **배경/필요성**: 비정형 데이터와 대량 트래픽이 늘면서 고정 스키마와 복합 조인 중심 구조만으로는 처리량과 개발 유연성을 맞추기 어려워 다양한 저장 모델이 필요해짐

## Ⅱ. 특징

- 문서형은 JSON 유사 구조로 유연한 속성 확장에 강함
- 키값형은 단순 조회와 세션성 데이터 처리에 매우 빠름
- 컬럼형은 대규모 분산 쓰기와 분석 집계에 유리함
- 그래프형은 관계 탐색과 경로 질의에 강하지만 범용 트랜잭션 대체재는 아님

## Ⅲ. 종류 및 비교

| 판단 기준 | 문서형 | 키값형 | 컬럼형 | 그래프형 |
|:---|:---|:---|:---|:---|
| 데이터 구조 | 문서 단위 | key-value | column family | 노드·엣지 |
| 강점 | 유연한 스키마 | 초고속 lookup | 분산 확장과 집계 | 관계 탐색 |
| 한계 | 복잡 조인 약함 | 질의 표현력 낮음 | 모델링 난도 | 대량 범용 처리 제한 |
| 적합 업무 | 콘텐츠·프로필 | 세션·캐시 | 로그·시계열 | 추천·관계 분석 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Data Model | 저장 단위와 관계 표현 방식을 정해 질의 특성을 결정함 |
| Distribution Strategy | 파티셔닝과 복제로 확장성과 가용성을 확보함 |
| Consistency Policy | 즉시 일관성과 최종 일관성 사이의 선택을 구체화함 |
| Query Interface | API와 질의 언어 수준이 개발 생산성과 운영 유연성에 영향을 줌 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 특성 분석 | --> | 저장 모델 선택  | --> | 분산/일관성 설계 | --> | 운영 지표 검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 특성 분석**: 구조와 접근 패턴과 성장 방향을 파악함
2. **저장 모델 선택**: 문서형과 키값형과 컬럼형과 그래프형을 비교함
3. **분산과 일관성 설계**: 복제와 파티셔닝과 정합성 수준을 정함
4. **운영 지표 검증**: 지연과 확장성과 불일치를 측정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 데이터 모델보다 유행과 제품명만 보고 NoSQL을 선택하면 질의와 일관성 요구를 맞추지 못할 수 있음
   - 해결방안: access pattern 기반 선택을 수행하고 model fit score와 query rewrite rate로 검증함
2. 문제: 관계형 사고를 그대로 가져와 애플리케이션 조인을 남발하면 분산 환경에서 응답 지연이 급증할 수 있음
   - 해결방안: denormalized read model을 설계하고 cross-entity join ratio와 p95 latency로 검증함
3. 문제: 최종 일관성 특성을 문서화하지 않으면 개발과 운영이 서로 다른 정합성 기대를 가질 수 있음
   - 해결방안: consistency contract를 명시하고 stale data incident count와 expectation mismatch rate로 검증함

## Ⅶ. 적용 사례

- 콘텐츠 플랫폼에서는 데이터 모델 적합성을 검토하고 확인 지표는 model fit score와 query rewrite rate임
- 대규모 사용자 세션 서비스에서는 읽기 모델을 단순화하고 확인 지표는 cross-entity join ratio와 p95 latency임
- 분산 상품 카탈로그에서는 정합성 계약을 명시하고 확인 지표는 stale data incident count와 expectation mismatch rate임

## Ⅷ. 결론

NoSQL 선택의 핵심은 관계형을 대체하는 데 있지 않고 데이터 구조와 접근 패턴에 맞는 저장 모델을 분산 운영 전제로 고르는 데 있음.
