## 미리 알고가기

- WebAssembly는 여러 언어의 이식 가능한 컴파일 대상으로 설계된 바이너리 명령 형식임
- 서버사이드 WASM은 브라우저 밖의 독립 런타임이나 서버 애플리케이션에 내장해 모듈을 실행함
- 선형 메모리는 WASM 인스턴스가 접근하는 경계 검사 대상 메모리 공간임
- import·export는 WASM 모듈이 호스트와 기능을 주고받는 명시적 인터페이스임
- WASI는 파일·네트워크·시계 같은 시스템 기능을 권한 기반 인터페이스로 제공함
- 컴포넌트 모델은 WIT 인터페이스와 Canonical ABI로 언어 간 조합 규약을 제공함

## 작성 근거(검토용)

- 서버사이드 WASM은 이식 가능한 모듈, 선형 메모리, 명시적 import, 런타임, WASI를 핵심 축으로 설명함
- 비교표는 실행·격리 단위, 시스템 접근·이식성, 적합 조건의 정확히 3개 축을 대비함
- 절차는 모듈 검증·실행 준비·권한 연결·인스턴스화·함수 호출과 trap 반환 순서를 따름

## Ⅰ. 개요

- **정의/개념**: 서버사이드 WASM은 컴파일된 WASM 모듈을 브라우저 밖 런타임에서 검증·인스턴스화하고 허용한 호스트 기능만 연결해 실행하는 방식임
- **배경/필요성**: 다중 언어 확장 코드를 서버 애플리케이션의 메모리·권한과 분리하기 위해 이식 가능한 샌드박스가 필요함

### 쉽게 이해하기 (학습용)
- 서버사이드 WASM은 여러 언어로 만든 모듈을 제한된 메모리와 권한 안에서 실행함

## Ⅱ. 특징

- WASM 명령과 선형 메모리 접근은 런타임의 형식·경계 검사를 거침
- 모듈은 import로 연결된 호스트 함수와 WASI 권한만 사용할 수 있음
- 같은 모듈을 지원 런타임과 시스템 인터페이스 범위에서 여러 OS·아키텍처에 배치할 수 있음
- CPU·메모리·실행 시간 제한과 호스트 함수 설계가 실제 격리 강도를 결정함

### 쉽게 이해하기 (학습용)
- 모듈은 호스트가 열어 준 함수와 WASI 기능만 사용할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 서버사이드 WASM | OS 컨테이너 |
|:---|:---|:---|
| 실행·격리 단위 | 모듈·컴포넌트를 선형 메모리와 import 경계에서 실행 | 이미지·파일시스템·프로세스를 namespace·cgroup으로 격리 |
| 시스템 접근·이식성 | WASI·호스트 함수만 허용하며 인터페이스 호환으로 이식 | 시스템 호출·마운트를 사용하며 OS·CPU·이미지 호환 필요 |
| 적합 조건 | 비신뢰 플러그인·다중 언어 확장 | 기존 서버 프로그램과 넓은 OS 기능 실행 |

> 요약: 서버사이드 WASM은 선형 메모리와 명시적 import 경계에서 이식 가능한 모듈을 실행함.

### 쉽게 이해하기 (학습용)
- WASM은 작은 기능 모듈, 컨테이너는 운영체제 기능을 쓰는 전체 프로세스 실행에 적합함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| WASM 모듈·컴포넌트 | 컴파일된 함수·메모리·import·export와 인터페이스를 담음 |
| WASM 런타임 | 모듈을 검증·실행 준비·인스턴스화하고 실행 자원을 제한함 |
| 선형 메모리·테이블 | 모듈 데이터와 함수 참조를 격리된 주소 범위에 저장함 |
| 호스트 함수 | 애플리케이션이 허용한 기능만 모듈 import에 연결함 |
| WASI | 파일·네트워크·시계·난수 같은 시스템 인터페이스를 제공함 |
| WIT·컴포넌트 모델 | 언어 간 타입과 호출 규약을 정의해 컴포넌트를 조합함 |

```text
호스트 애플리케이션 -> WASM 런타임 -> 모듈·선형 메모리
                           |
WIT import·export ----------+-> WASI·호스트 함수 -> 허용 자원
```

> 요약: 런타임이 모듈 메모리를 격리하고 호스트는 import·WASI 인터페이스로 권한을 제공함.

### 쉽게 이해하기 (학습용)
- 런타임·선형 메모리·WASI·호스트 함수가 실행과 권한 경계를 만듦

## Ⅴ. 원리 및 절차 흐름도

```text
모듈 로드 -> 형식·코드 검증 -> 실행 코드 준비 -> import·권한 연결 -> 인스턴스화 -> 호출·반환
```

1. **모듈 로드**: 런타임이 WASM 바이너리와 인터페이스 정의를 읽음
2. **검증·실행 준비**: 명령·타입·메모리 규칙을 검사하고 런타임 방식에 맞는 실행 형태로 준비함
3. **권한 연결**: 호스트가 허용한 함수와 WASI 자원을 import에 연결함
4. **인스턴스화**: 런타임이 선형 메모리·테이블·실행 상태를 생성함
5. **호출·반환**: 호스트가 export 함수를 호출하고 결과 또는 trap을 받음

> 요약: 검증된 모듈에 허용한 import와 WASI 권한을 연결한 뒤 격리된 인스턴스로 실행함.

### 쉽게 이해하기 (학습용)
- 모듈 검증 후 필요한 권한만 연결하고 호출 결과나 trap을 반환함

## Ⅵ. 실무 사례

1. API 게이트웨이 플러그인은 WASM import를 제한하고 초기화 지연·메모리 사용량을 확인함
2. 다중 언어 확장 모듈은 WIT 계약으로 조합하고 인터페이스 테스트 실패·호출 지연을 확인함

### 쉽게 이해하기 (학습용)
- 플러그인 권한 위반과 언어 간 인터페이스 호환성을 함께 시험함

## Ⅶ. 결론

- 서버사이드 WASM은 모듈 이식성과 권한 격리가 필요하고 WASI·호스트 함수 범위를 통제할 때 적용함

### 쉽게 이해하기 (학습용)
- 빠른 실행보다 허용 기능과 런타임 호환 범위를 명확히 정하는 것이 중요함
