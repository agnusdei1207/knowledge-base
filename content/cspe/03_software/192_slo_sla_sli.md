## 미리 알고가기

- SLI는 사용자가 경험한 성공률·지연·신선도 같은 서비스 동작을 측정한 값임
- SLO는 정한 기간에 SLI가 달성해야 할 내부 신뢰성 목표임
- SLA는 제공자와 고객이 서비스 수준과 미달 시 책임·보상을 합의한 계약임
- 좋은 이벤트는 SLI 기준을 충족한 요청이고 유효 이벤트는 측정 대상 전체 요청임
- 오류 예산은 $1-SLO$에 해당하는 허용 실패 비율이며 내부 운영 판단에 사용함
- 측정 위치가 사용자 경로에서 멀면 실제 사용자 경험과 SLI가 달라질 수 있음

## 작성 근거(검토용)

- SLI·SLO·SLA는 측정값·내부 목표·외부 계약의 역할과 연결 관계를 핵심 축으로 설명함
- 비교표는 역할·표현·정의 주체·판정 결과·적용 목적을 같은 질문으로 대비함
- 구조는 서비스 경계에서 SLI를 측정하고 SLO·오류 예산과 SLA 판단으로 연결하는 관계를 제시함

## Ⅰ. 개요

- **정의/개념**: SLI는 서비스 동작 측정값, SLO는 SLI의 내부 목표, SLA는 고객과 합의한 서비스 수준과 미달 책임임
- **배경/필요성**: 사용자 기대와 운영 목표·계약 책임을 같은 서비스 측정값에 연결하기 위해 SLI·SLO·SLA 구분이 필요함

## Ⅱ. 특징

- SLI는 성공 요청 비율·임계시간 내 응답 비율처럼 좋은 이벤트와 유효 이벤트의 비율로 정의할 수 있음
- SLO는 SLI 임계값·목표 비율·측정 기간을 함께 정해야 판정할 수 있음
- SLA는 계약 대상·측정 방식·제외 조건·미달 시 보상과 책임을 명시함
- 내부 SLO를 SLA보다 엄격하게 정하면 계약 위반 전에 대응할 여지를 확보함

## Ⅲ. 종류 및 비교

| 판단 기준 | SLI | SLO | SLA |
|:---|:---|:---|:---|
| 역할 | 서비스 동작을 측정 | 신뢰성 목표를 설정 | 제공 수준과 책임을 합의 |
| 표현 | 성공률·지연·신선도 측정값 | SLI 임계값·목표 비율·기간 | 목표·측정법·제외·보상 조건 |
| 정의·합의 주체 | 서비스 운영·개발 팀이 측정법 정의 | 제품·개발·SRE가 목표 합의 | 제공자와 고객이 계약 |
| 판정 결과 | 측정값·추세 생성 | SLO 준수·오류 예산 소진 판정 | 서비스 크레딧·보상·계약 조치 발생 |
| 주요 목적 | 사용자 경험을 수치화 | 변경 속도와 신뢰성 균형 | 외부 서비스 수준과 책임 확정 |
| 대표 예 | 성공 요청 비율 | 30일간 성공 요청 99.9% | 월 성공률이 계약 목표 미달 시 크레딧 제공 |

> 요약: SLI로 서비스 동작을 측정하고 SLO로 내부 목표를 정하며 SLA로 외부 책임을 합의함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 서비스 경계 | 사용자 요청과 측정 대상·제외 범위를 정함 |
| SLI 명세 | 좋은 이벤트·유효 이벤트·임계값·측정 위치를 정의함 |
| SLO 문서 | 목표 비율·기간·검토 주기·오류 예산 계산법을 기록함 |
| 오류 예산 정책 | SLO 미달 위험에 따른 배포·복구·개선 조건을 정함 |
| SLA 계약 | 고객 범위·측정 자료·제외 조건·보상 기준을 합의함 |

```text
사용자 요청 -> SLI 측정 -> SLO·오류 예산 -> 내부 운영 판단
                  |
                  +-> SLA 기준 비교 -> 계약 책임 판단
```

> 요약: 같은 서비스 측정값이 내부 SLO·오류 예산과 외부 SLA의 서로 다른 판단에 사용됨.

## Ⅵ. 실무 사례

1. API는 300ms 이내 성공 비율을 SLI로 두고 SLO 준수율·오류 예산 소진율을 확인함
2. 데이터 파이프라인은 10분 이내 결과 비율을 SLI로 두고 신선도 SLO·지연 건수를 확인함

## Ⅶ. 결론

- SLI·SLO·SLA는 사용자 측정 위치·방식을 명확히 하고 내부 목표와 계약 책임을 구분해 운영함
