## Ⅰ. 개요
- **정의**: 대규모 데이터를 Map과 Reduce 두 단계로 분할-병합 처리하는 분산 프로그래밍 모델
- **배경/필요성**: 단일 노드로 처리 불가능한 규모의 데이터를 다수 노드에서 병렬 처리할 체계가 필요함
- **비유**: 시험지 채점을 여러 조교가 과목별로 나눠 채점(Map)한 뒤 총점을 합산(Reduce)하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 분산 병렬 처리 원리 이해 | Map-Shuffle-Reduce 3단계 흐름 | Shuffle/Sort 단계 누락 금지 |

> 요약: 대규모 데이터를 Map-Shuffle-Reduce 파이프라인으로 분산 병렬 처리하는 모델임

## Ⅱ. 구성요소
```text
Input --> Splitter --> [Map] --> Shuffle/Sort --> [Reduce] --> Output
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Map | 입력 데이터를 Key-Value 쌍으로 변환하는 함수 | 원재료를 부품별로 분류하는 작업자 |
| Shuffle/Sort | 동일 Key를 가진 데이터를 같은 Reduce 노드로 재배치함 | 같은 과목 답안지를 한 조교에게 모으는 과정 |
| Reduce | 동일 Key의 Value 목록을 집계하여 최종 결과를 생성함 | 모인 답안지의 점수를 합산하는 조교 |
| Splitter | 입력 파일을 고정 크기 블록으로 분할함 | 시험지를 일정 매수씩 나누는 행위 |

> 요약: Input을 분할-변환-재배치-집계하는 네 가지 구성요소로 동작함

## Ⅲ. 절차
```text
Input Split --> Map Phase --> Shuffle/Sort --> Reduce Phase
    |               |              |               |
    v               v              v               v
 블록분할      KV쌍 변환      키별 그룹핑      집계/출력
```
- 1단계: Splitter가 입력 데이터를 고정 크기 블록으로 분할함
- 2단계: 각 Map 태스크가 블록을 읽어 Key-Value 쌍을 생성함
- 3단계: Shuffle/Sort가 동일 Key 데이터를 동일 Reduce 노드로 전송함
- 4단계: Reduce 태스크가 Key별 Value를 집계하여 최종 결과를 출력함

> 요약: 분할-매핑-셔플-리듀스 4단계를 순차적으로 수행하여 결과를 산출함

## Ⅳ. 문제점
- 디스크 I/O 병목: 중간 결과를 디스크에 기록하여 반복 연산 시 지연이 큼
- 반복 처리 비효율: 단일 패스 구조로 ML 등 반복 알고리즘에 부적합함
- 실시간 처리 불가: 배치 기반이므로 저지연 스트림 처리 요구에 대응 불가함

> 요약: 디스크 의존·반복 처리·실시간 미지원이 주요 한계임

## Ⅴ. 개선방안
1. 단기: 인메모리 캐싱 도입으로 디스크 I/O 감소 (Apache Spark RDD 등)
2. 중기: DAG 기반 실행 엔진 전환으로 반복 처리 효율화
3. 장기: 스트림 처리 프레임워크(162 참조)와 통합하여 실시간 파이프라인 구축

> 요약: 인메모리 처리-DAG 엔진-스트림 통합 순으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 배치-스트림 통합(Lambda/Kappa Architecture)으로 수렴 중임
- 기술사적 판단: 분산 처리 기본 패러다임으로서 학습 가치가 유지됨
- 기술사 제언: 워크로드 특성에 따라 배치/스트림 엔진을 선택·혼용할 설계 역량이 필요함
