## Ⅰ. 개요
- 정의: 지리적으로 분산된 여러 서버에 콘텐츠를 복제하여 사용자 근거리에서 전송하는 기술.
- 출제 의도: 글로벌 서비스의 지연 시간 단축 및 트래픽 폭주 대응을 위한 인프라 기술 이해 확인.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Origin Server ] (Source)
         |
  [ Edge Location 1 ] [ Edge Location 2 ] [ Edge Location 3 ]
         |                   |                   |
  [ User A (SEOUL) ]  [ User B (LA) ]     [ User C (LONDON) ]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Origin Server | 원본 콘텐츠를 보관하고 있는 중앙 서버 | 본사 창고 |
| Edge Server | 사용자 부근에 위치하여 콘텐츠를 캐싱 및 배달하는 서버 | 지역 대리점 |
| POP (Point of Presence) | 엣지 서버들이 물리적으로 위치한 거점 지점 | 유통 거점 |
> 요약: 거리가 멀수록 느린 인터넷의 물리적 한계를 '근거리 복제'로 극복함.

## Ⅲ. 절차
- ASCII 흐름도
  [DNS 조회] -> [최적 엣지 선정] -> [캐시 확인/전달] -> [미존재 시 원본 요청]
- 4단계 설명
1. 사용자가 URL 요청 시 DNS가 사용자 IP 기반으로 가장 가까운 엣지 IP 응답함.
2. 엣지 서버에 요청한 정적/동적 자원이 이미 저장되어 있는지 확인함.
3. 데이터가 존재하면 즉시 응답하고, 없으면 원본 서버에서 데이터를 가져옴.
4. 원본에서 가져온 데이터를 향후 요청을 위해 엣지 서버에 일정 기간 보관함.
> 요약: 전송 경로(Hop)를 최소화하여 사용자 체감 속도를 향상시킴.

## Ⅳ. 문제점
- 콘텐츠 동기화: 원본 데이터 수정 시 전 세계 엣지에 반영되는 데 시간차(Purge 지연) 발생함.
- 비용 증가: 전송량(Egress)에 따라 과금되므로 대용량 파일 전송 시 비용 부담 커짐.

## Ⅴ. 개선방안
- 무효화(Purge) 최적화: API를 통해 변경된 자원만 즉시 삭제하거나 버전닝(Versioning) 활용함.
- 멀티 CDN: 여러 CDN 벤더를 혼용하여 특정 지역 장애 대응 및 비용 경쟁 유도함.

## Ⅵ. 전망
- 보안 기능(WAF, Bot 방어)이 결합된 'Edge Security' 서비스로의 통합 가속화됨.
- 단순 캐싱을 넘어 엣지에서 코드를 실행하는 'Edge Computing' 플랫폼으로 진화 중임.
- 고화질 영상 스트리밍 및 VR/AR 확산에 따라 5G 망 내부 엣지 활용 사례가 증대될 것임.
