## 미리 알고가기

- Saga 패턴(Saga Pattern): 여러 독립된 서비스에 걸친 비즈니스 트랜잭션을 로컬 트랜잭션의 연쇄로 관리하는 분산 트랜잭션 패턴임
- 보상 트랜잭션(Compensating Transaction): 이전 단계에서 커밋된 로컬 트랜잭션의 효과를 업무적으로 상쇄(되돌림)하는 취소 트랜잭션임
- 2단계 커밋(2PC, Two-Phase Commit): 분산 데이터베이스 환경에서 모든 노드가 원자성을 보장하기 위해 준비(Prepare)와 커밋(Commit) 단계를 거치는 동기식 프로토콜임
- 오케스트레이션(Orchestration): 중앙의 조정자(Orchestrator)가 각 서비스에 보낼 메시지와 흐름을 직접 제어하는 방식임
- 코레오그래피(Choreography): 중앙의 조정자 없이 각 서비스가 도메인 이벤트를 발행·구독하며 자율적으로 통신하는 방식임
- 멱등성(Idempotency): 동일한 요청을 여러 번 전송하더라도 시스템 상태가 최초 1회 처리와 동일하게 유지되는 성질임
- 상관관계 ID(Correlation ID): 분산 호출 경로 상의 여러 이벤트를 하나의 비즈니스 트랜잭션으로 묶기 위해 사용하는 공통 식별자임

## 작성 근거(검토용)

- Saga는 흐름 제어, 상태 추적, 결합도를 핵심 비교축으로 선정함
- 구성과 절차는 로컬 트랜잭션 실패 후 보상 실행까지의 상태 전이를 중심으로 제시함
- 실무 판단은 보상 성공률, 데이터 불일치 건수, 중복 실행률로 구체화함
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정함.

## Ⅰ. 개요

- **정의/개념**: Saga는 여러 서비스의 업무 흐름을 로컬 트랜잭션과 보상 트랜잭션의 연속으로 처리하는 분산 트랜잭션 패턴임
- **배경/필요성**: MSA에서 2단계 커밋은 성능·가용성 부담이 크므로 서비스별 저장소를 유지하며 업무 일관성을 회복할 방식이 필요함

### 쉽게 이해하기 (학습용)
- 여러 부서가 결재판을 돌려보며 일할 때, 중간에 거절당하면 여태까지 결재받은 서류들을 취소하거나 복구하는 규칙(보상 트랜잭션)을 만들어 업무를 마무리하는 방식임.

## Ⅱ. 특징

- 각 서비스가 독립 저장소를 유지하면서도 하나의 업무 흐름을 이어갈 수 있음
- 각 로컬 트랜잭션 커밋 후 실패하면 이전 단계의 업무 효과를 보상 트랜잭션으로 취소함
- 오케스트레이션은 조정자가 단계 상태를 기록하고, 코레오그래피는 서비스가 이벤트를 구독해 다음 단계를 실행함
- 외부 송금·수동 승인처럼 자동 취소할 수 없는 단계가 포함되면 보상 방식이 제한됨

### 쉽게 이해하기 (학습용)
- 한 번에 모든 데이터베이스를 잠그지 않고 각자 일을 처리하되, 실패하면 이전에 완료된 일들을 역순으로 취소하여 시스템 전체의 모순을 해결함.

## Ⅲ. 종류 및 비교

| 판단 기준 | 오케스트레이션 | 코레오그래피 |
|:---|:---|:---|
| 제어 메커니즘 | 중앙 조정자(Orchestrator)가 전체 제어 흐름과 보상 절차를 중재함 | 각 서비스가 도메인 이벤트를 발행·구독하여 자율적으로 흐름을 전개함 |
| 결합도 및 복잡도 | 조정자가 개별 서비스를 알아야 하므로 결합도가 높지만 흐름이 단순함 | 서비스 간 의존성이 낮아 결합도가 낮으나 전체 흐름 분석이 복잡함 |
| 흐름 추적 및 모니터링 | 중앙 조정자의 내부 상태를 통해 트랜잭션 진행 상황을 즉시 확인 가능함 | 상관관계 ID($Correlation\ ID$) 기반 분산 추적 도구로 로그를 병합해야 함 |

> 요약: 중앙에서 단계와 보상을 제어하면 오케스트레이션, 서비스가 이벤트에 반응하면 코레오그래피 방식임.

### 쉽게 이해하기 (학습용)
- 중앙에 비서를 두고 일의 단계와 취소를 총괄 지시하게 할지(오케스트레이션), 각 부서가 앞 부서의 완료 보고를 듣고 다음 일을 스스로 알아서 할지(코레오그래피)의 차이임.

## Ⅳ. 설계 요소 및 구조

```text
[Saga Orchestrator] ──(1. 주문 생성 명령)──> [주문 서비스]
                    <──(2. 주문 완료 이벤트)───
                    ──(3. 결제 처리 명령)──> [결제 서비스 (실패!)]
                    ──(4. 주문 취소 보상)──> [주문 서비스]
```

| 설계 요소 | 설명 |
|:---|:---|
| 로컬 트랜잭션 | 각 서비스 저장소에서 원자적으로 수행되는 작업 단위임 |
| 보상 동작 | 실패 시 이전 단계의 업무 효과를 되돌려 일관성을 회복함 |
| 조정자·이벤트 흐름 | 중앙 조정자나 이벤트가 전체 진행 순서를 연결함 |
| 상태 추적 | 현재 단계와 실패 위치를 기록해 재시도와 보상 대상을 결정함 |

> 요약: 로컬 트랜잭션의 진행 상태를 추적하고 실패 지점 이전의 완료 단계를 역순으로 보상함.

### 쉽게 이해하기 (학습용)
- 자기 일을 처리하는 부서(로컬 트랜잭션), 일이 잘못되었을 때 쓰는 지우개(보상 트랜잭션), 전체 진행 상황을 지켜보는 관리대장(상태 추적)으로 나뉨.

## Ⅴ. 원리 및 절차 흐름도

```text
단계 실행 ──> 다음 단계 전달 ──> 실패 감지 ──> 보상 수행
```

1. **단계 실행**: 첫 서비스가 로컬 트랜잭션을 수행함
2. **다음 단계 전달**: 중앙 조정자나 이벤트로 다음 서비스에 흐름을 넘김
3. **실패 감지**: 어느 단계에서 실패했는지 상태를 확인함
4. **보상 수행**: 이미 끝난 단계들을 규칙에 따라 되돌림

> 요약: 각 단계의 로컬 트랜잭션을 순차 실행하고 실패하면 완료된 단계의 보상을 역순으로 수행함.

### 쉽게 이해하기 (학습용)
- 1단계가 완료되면 2단계로 넘어가고, 3단계에서 실패가 나면 이미 지나온 2단계와 1단계를 차례로 되돌려 일을 없었던 것으로 만드는 흐름임.

## Ⅵ. 실무 사례

전자상거래 및 물류 배송 시스템에서 주문, 결제, 재고 차감에 이르는 긴 비즈니스 트랜잭션을 일관되게 처리하기 위해 오케스트레이션 기반 Saga 패턴을 설계하여 결제 실패 시 재고 복구 및 주문 취소 보상 트랜잭션을 연쇄 실행함. 메시지 브로커를 통한 비동기 통신 환경에서 보상 트랜잭션의 중복 실행을 방지하고자 상관관계 ID를 이용한 데이터 멱등성 검증 필터를 적용함.

### 쉽게 이해하기 (학습용)
- 항공권 예약 중 좌석 선택과 결제는 되었으나 호텔 예약에서 실패했을 때, 결제를 취소하고 선택했던 좌석을 다시 빈자리로 돌려놓는 보상 작용을 자동 처리함.

## Ⅶ. 결론

- Saga 패턴은 분산 아키텍처 환경에서 기존 동기식 2단계 커밋의 블로킹 문제를 극복하고, 보상 트랜잭션을 통해 업무적 데이터 일관성을 종국에 회복하도록 돕는 유연한 해법임.
- 완벽한 롤백이 불가한 물리적 외부 연동이나 보상 트랜잭션의 재시도 실패 상황을 감안하여 한계 조건을 정의하고, 최종 일관성이 깨졌을 때의 수동 보정 및 알림 절차를 구비해야 함.

### 쉽게 이해하기 (학습용)
- Saga 패턴은 분산 시스템에서 시스템 멈춤 없이 업무를 끝내게 해주며, 취소가 불가능한 상황에 대비해 최종 경고와 관리자 개입 수단을 마련하는 것이 중요함.
