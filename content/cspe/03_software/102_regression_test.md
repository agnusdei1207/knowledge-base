## Ⅰ. 개요
- 정의: Regression Test의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Code Change] -> [Old Tests] -> [Verify No Regression]
                          |
                          +---> [Fail] -> [Debug]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 선택적 테스트 | 변경된 부분과 관련된 기능만 수행 | 핀포인트 |
| 전체 테스트 | 시스템 전체 기능을 재수행 | 전수 조사 |
| 파급 효과 분석 | 변경이 미치는 영향 범위를 식별 | 파편 분석 |

> 요약: SW 수정 후 기존 기능의 무결성을 재검증하는 활동임.

## Ⅲ. 절차
- ASCII 흐름도
  Modify -> Impact Analysis -> Select TC -> Execute -> Report

1. 변경 영향 분석: 소스 수정 및 종속성 분석을 통한 범위 산정함.
2. 테스트 케이스 선정: 기존 케이스 중 재수행 대상 선별함.
3. 테스트 수행: 자동화 도구 활용하여 반복 테스트 실시함.
4. 결함 조치: 발견된 리그레션 결함 수정 및 재확인함.

> 요약: 변경에 의한 예기치 못한 부작용(Side Effect) 방지임.

## Ⅳ. 문제점
- 개발 주기 반복에 따른 테스트 케이스 누적으로 수행 시간 증가함.
- 수동 수행 시 반복 작업에 의한 테스터 피로도 및 누락 발생함.

## Ⅴ. 개선방안
- 테스트 자동화 파이프라인 구축으로 수행 비용 최소화함.
- 우선순위 기반 TC 최적화 및 불필요한 케이스 주기적 정리함.

## Ⅵ. 전망
- 애자일 및 CI/CD 환경의 핵심으로 자동화된 회귀 테스트 필수화됨.
- CSF: 변경 영향 분석 자동화 도구 도입 및 TC 유지보수 프로세스임.
