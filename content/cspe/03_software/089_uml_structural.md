## Ⅰ. 개요
- 시스템의 정적인 구조와 구성 요소들 사이의 관계를 시각적으로 표현한 것임.
- 객체지향 분석/설계(OOAD)의 핵심 도구로 논리적 모델링에 사용됨.
- 출제 의도: 클래스 간의 다양한 관계(상속, 포함 등)와 표기법의 정확성 확인.

## Ⅱ. 구성요소
- 클래스 다이어그램 관계
[Class A] <--- [Relationship] ---> [Class B]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Generalization | 부모와 자식 클래스 간의 상속 관계 (is-a) | 부모와 자녀 |
| Composition | 강한 포함 관계, 부모 소멸 시 자식도 소멸함 | 자동차와 엔진 |
| Aggregation | 약한 포함 관계, 독립적 생명 주기 가짐 (has-a) | 가방과 책 |
> 요약: 클래스의 속성, 메서드 및 정적 연관성을 정의함.

## Ⅲ. 절차
- 구조적 모델링 수행 단계
[Entity Extraction] -> [Attribute/Method] -> [Relating] -> [Refinement]

1. 개체 추출: 문제 영역에서 명사를 찾아 후보 클래스를 도출함.
2. 속성 정의: 각 클래스가 가져야 할 데이터와 기능을 명세함.
3. 관계 설정: 클래스 간의 연관, 의존, 일반화 관계를 화살표로 연결함.
4. 다중도 지정: 관계의 수(1:1, 1:N, N:M)를 기입하여 상세화함.
> 요약: 개별 요소들의 정적 연결 구조를 완성하여 설계도를 작성함.

## Ⅳ. 문제점
- 과도한 상세화로 인한 다이어그램 복잡도 상승 및 코드와의 불일치 발생.

## Ⅴ. 개선방안
- 핵심 아키텍처 중심의 추상화 유지 및 CASE 도구를 이용한 자동 동기화.

## Ⅵ. 전망
- 모델 기반 개발(MDD)을 통한 UML 설계의 실행 가능한 코드 자동 변환 가속.
- 대규모 마이크로서비스 간의 정적 의존 관계를 시각화하는 도구로 진화 중.
