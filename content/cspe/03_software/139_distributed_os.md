## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 여러 독립된 컴퓨터들을 통신망으로 연결하여 단일 시스템처럼 관리하는 OS |
| 필요성 | 자원 공유, 연산 속도 향상, 신뢰성(결함 허용) 및 확장성 확보 |
| 출제 의도 | 투명성(Transparency), NOS vs DOS 차이, 일관성 유지 기법 이해 |

## Ⅱ. 구성요소
```text
[   Application   ]
+-----------------+
|  Distributed OS | <-- (IPC / RPC)
+-----------------+
| Node1 | Node2 | Node3 | (Network)
```
| 구성요소 | 설명 | 판단 기준 |
|---|---|---|
| 투명성 | 사용자에게 분산 자원의 위치·이동·복제·장애 처리를 숨김 | 노출되는 분산 속성 |
| RPC | 요청·직렬화·전송·응답으로 원격 프로시저를 호출함 | 원격 호출 경로 |
| 일관성 제어 | 복제본의 연산 순서·버전·충돌 규칙을 조정함 | 복제 상태 수렴 |
> 요약: 분산 OS의 핵심 가치는 위치, 이주, 장애 등에 대한 투명성 제공임.

## Ⅲ. 절차
```text
User Request -> Global Name Service -> Locate Node -> Remote Call
      ^                                                  |
      +----- Result Aggr <----- Data Proc <----- Dispatch +
```
1. 요청 접수: 사용자가 특정 파일이나 연산을 시스템에 요청.
2. 위치 확인: 전역 이름 서비스(Naming Service)를 통해 자원의 물리 위치 파악.
3. 원격 실행: RPC 또는 메시지 전달을 통해 해당 노드에 작업 할당.
4. 결과 취합: 분산 처리된 결과를 수집하여 사용자에게 최종 응답 반환.
> 요약: 분산 OS는 원격 자원 위치를 해석하고 작업을 배치하며 통신 실패·노드 장애 시 재시도·재배치를 수행함.

## Ⅳ. 문제점
- 네트워크 지연(Latency) 및 신뢰성 결여로 인한 성능 예측 불가성.
- 부분 장애(Partial Failure) 발생 시 전역 상태 일관성 파괴 및 복구 어려움.

## Ⅴ. 개선방안
- 원자적 분산 commit에는 2PC를, 복제 상태·leader 합의에는 Paxos·Raft 계열을 목적에 맞게 적용함.
- 분산 cache와 edge 배치 시 cache invalidation·stale data 허용 범위·원본 장애 동작을 정의함.

## Ⅵ. 전망
- 클라우드 네이티브: 컨테이너 오케스트레이션(K8s)이 실질적인 분산 OS 역할 수행.
- 서버리스(Serverless): 인프라 관리 없이 코드만 분산 실행하는 추상화 단계 고도화.
