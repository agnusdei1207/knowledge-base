## 미리 알고가기

- 관계형 데이터베이스는 데이터를 테이블 형태로 표현하고 관계를 키로 연결하는 데이터 모델임
- 릴레이션은 같은 속성 구조를 가진 행 집합이고 튜플은 테이블의 한 행을 뜻함
- SQL은 관계형 데이터베이스에서 조회와 갱신을 수행하는 대표 질의 언어임
- 무결성은 데이터가 중복과 모순 없이 의미 있는 상태를 유지하는 성질임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 관계형 데이터베이스는 릴레이션, 키, 무결성 제약, SQL·트랜잭션을 핵심 축으로 설명함
- 비교표는 관계형·비관계형 DB의 데이터 모델·관계 처리·제약·적합 업무를 대비함
- 주문·SaaS 데이터베이스는 무결성 위반 건수·느린 질의 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: 관계형 데이터베이스는 데이터를 릴레이션으로 표현하고 키·제약조건·SQL·트랜잭션으로 관계와 무결성을 관리하는 데이터 모델임
- **배경/필요성**: 업무 데이터의 중복·불일치와 동시 변경 오류를 줄이기 위해 구조화된 스키마와 일관된 조작 기준이 필요함

## Ⅱ. 특징

- 스키마와 제약조건으로 데이터 의미와 규칙을 명확히 표현함
- SQL과 조인으로 다양한 조회와 갱신을 지원함
- 트랜잭션과 키·참조·도메인 제약조건으로 동시 갱신과 데이터 관계를 통제함
- 스키마 변경과 대규모 수평 확장은 비정형 저장보다 제약이 더 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB | 비관계형 DB |
|:---|:---|:---|
| 데이터 모델 | 스키마 기반 테이블로 구조를 고정함 | 문서와 키값과 컬럼형처럼 다양한 구조를 사용함 |
| 관계·규칙 처리 | 키·조인·제약조건·트랜잭션으로 공통 규칙 관리 | 모델별 중첩·키 접근과 애플리케이션 규칙 관리 |
| 주요 한계 | 스키마 변경과 대규모 수평 확장에 부담이 생길 수 있음 | 복합 조인과 공통 제약 지원이 모델·제품마다 다름 |
| 대표 환경 | 관계·제약·트랜잭션이 필요한 업무 데이터 | 문서·키값·대규모 분산 접근이 필요한 데이터 |

> 요약: 관계형 DB는 스키마·키·제약조건으로 관계와 무결성을 관리하고, 비관계형 DB는 모델별 구조와 분산 접근을 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 릴레이션 | 동일한 속성 구조를 가진 행 집합으로 업무 데이터를 논리적으로 표현함 |
| 키 | 기본키와 외래키로 개체 식별과 관계 연결과 중복 방지를 수행함 |
| 제약조건 | 도메인과 개체와 참조 무결성을 강제해 데이터 품질을 유지함 |
| SQL 엔진 | 선언형 질의와 갱신을 처리해 저장 구조와 사용 질의를 연결함 |

> 요약: 릴레이션의 행을 키로 식별·연결하고 제약조건과 SQL 엔진이 데이터 무결성과 질의를 처리함.

## Ⅵ. 실무 사례

1. 주문 처리 DB는 기본키·외래키·도메인 제약을 적용하고 무결성 위반 건수·중복 데이터 비율을 확인함
2. SaaS 업무 DB는 실제 질의로 인덱스·실행 계획을 검증하고 느린 질의 비율·인덱스 사용률을 확인함

## Ⅶ. 결론

- 관계형 데이터베이스는 스키마·키·제약조건·트랜잭션으로 업무 데이터 관계와 무결성을 관리함
