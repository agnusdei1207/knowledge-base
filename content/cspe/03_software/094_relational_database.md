## 미리 알고가기

- 관계형 데이터베이스는 데이터를 테이블 형태로 표현하고 관계를 키로 연결함
- 릴레이션과 튜플과 속성은 관계형 모델의 기본 구성 단위임
- 무결성과 질의 언어와 트랜잭션이 함께 데이터 신뢰성을 뒷받침함

## Ⅰ. 개요

- **정의/개념**: 관계형 데이터베이스는 데이터를 속성 집합을 가진 테이블 형태의 릴레이션으로 저장하고 키와 제약조건과 SQL 연산을 통해 데이터 간 관계와 무결성을 관리하는 데이터 관리 모델임
- **배경/필요성**: 기업 정보 시스템에서는 데이터 중복과 불일치와 동시 변경 위험을 줄이면서도 다양한 질의를 안정적으로 처리해야 하므로, 구조화된 모델과 일관성 있는 조작 기준이 필요함

## Ⅱ. 특징

- 스키마와 제약조건을 통해 데이터 의미와 규칙을 명확히 표현함
- SQL 기반 질의와 조인으로 다양한 조회와 갱신을 지원함
- 트랜잭션과 무결성 관리로 일관된 데이터 처리가 가능함
- 스키마 변경과 수평 확장은 비정형 저장보다 상대적으로 제약이 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB | 비관계형 DB |
|:---|:---|:---|
| 데이터 모델 | 스키마 기반 테이블 | 문서·키값·컬럼 등 다양 |
| 강점 | 무결성·트랜잭션·복합 질의 | 확장성과 유연성 |
| 한계 | 스키마 경직성과 조인 비용 | 강한 일관성 설계 부담 |
| 적합 업무 | 핵심 업무 데이터 | 대규모 비정형·분산 데이터 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Relation | 동일한 속성 구조를 가진 행 집합으로 업무 데이터를 논리적으로 표현함 |
| Key | 기본키와 외래키로 개체 식별과 관계 연결과 중복 방지를 수행함 |
| Constraint | 도메인과 개체와 참조 무결성을 강제해 데이터 품질을 유지함 |
| SQL Engine | 선언형 질의와 갱신을 처리해 저장 구조와 사용 질의를 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스키마 정의     | --> | 데이터 저장     | --> | 질의/조인 수행  | --> | 무결성 유지     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스키마 정의**: 테이블과 키와 제약조건을 설계함
2. **데이터 저장**: 행 단위로 데이터를 삽입하고 갱신함
3. **질의와 조인 수행**: SQL로 조건 검색과 관계 조회를 처리함
4. **무결성 유지**: 제약과 트랜잭션으로 데이터 일관성을 보장함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 업무 규칙을 스키마에 반영하지 않으면 중복과 불일치 데이터가 빠르게 누적될 수 있음
   - 해결방안: key와 constraint 설계를 강화하고 integrity violation count와 duplicate record rate로 검증함
2. 문제: 조인과 인덱스 설계가 부적절하면 데이터는 정합해도 실제 질의 성능이 급격히 저하될 수 있음
   - 해결방안: workload 기반 인덱스와 실행 계획 점검을 수행하고 slow query ratio와 index hit rate로 검증함
3. 문제: 스키마 변경 절차가 약하면 운영 데이터와 애플리케이션 버전이 충돌할 수 있음
   - 해결방안: migration governance를 적용하고 migration success rate와 schema drift count로 검증함

## Ⅶ. 적용 사례

- 금융 계정계 시스템에서는 무결성 중심 설계를 적용하고, integrity violation count와 duplicate record rate로 결과를 확인함
- 전자상거래 주문 시스템에서는 질의 최적화를 수행하고, slow query ratio와 index hit rate로 결과를 확인함
- SaaS 제품팀에서는 스키마 변경 거버넌스를 운영하고, migration success rate와 schema drift count로 결과를 확인함

## Ⅷ. 결론

관계형 데이터베이스의 본질은 테이블 저장 그 자체보다 구조화된 스키마와 무결성과 트랜잭션으로 핵심 업무 데이터를 신뢰 가능하게 다루는 데 있음.
