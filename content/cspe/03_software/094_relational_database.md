## 미리 알고가기

- 관계형 데이터베이스는 데이터를 테이블 형태로 표현하고 관계를 키로 연결하는 데이터 모델임
- 릴레이션은 같은 속성 구조를 가진 행 집합이고 튜플은 테이블의 한 행을 뜻함
- SQL은 관계형 데이터베이스에서 조회와 갱신을 수행하는 대표 질의 언어임
- 무결성은 데이터가 중복과 모순 없이 의미 있는 상태를 유지하는 성질임

## Ⅰ. 개요

- **정의/개념**: 관계형 데이터베이스는 데이터를 속성 집합을 가진 테이블 형태의 릴레이션으로 저장하고 키와 제약조건과 SQL 연산을 통해 데이터 간 관계와 무결성을 관리하는 데이터 관리 모델임.
- **배경/필요성**: 기업 정보 시스템에서는 데이터 중복과 불일치와 동시 변경 위험을 줄이면서도 다양한 질의를 안정적으로 처리해야 하므로, 구조화된 데이터 모델과 일관된 조작 기준이 필요함.

## Ⅱ. 특징

- 스키마와 제약조건으로 데이터 의미와 규칙을 명확히 표현함
- SQL과 조인으로 다양한 조회와 갱신을 지원함
- 트랜잭션과 무결성 관리로 핵심 업무 데이터를 안정적으로 다룰 수 있음
- 스키마 변경과 대규모 수평 확장은 비정형 저장보다 제약이 더 큼

## Ⅲ. 종류 및 비교

| 구분 | 관계형 DB | 비관계형 DB |
|:---|:---|:---|
| 데이터 모델 | 스키마 기반 테이블로 구조를 고정함 | 문서와 키값과 컬럼형처럼 다양한 구조를 사용함 |
| 얻는 장점 | 무결성과 트랜잭션과 복합 질의에 강함 | 확장성과 유연한 구조 대응에 강함 |
| 주요 한계 | 스키마 경직성과 조인 비용이 부담이 될 수 있음 | 강한 일관성과 복합 관계 처리가 어려울 수 있음 |
| 적합한 상황 | 핵심 업무 데이터와 정합성 중심 시스템에 적합함 | 대규모 비정형 데이터와 분산 중심 환경에 적합함 |

> 요약: 관계형 데이터베이스의 본질은 테이블 저장보다 구조화된 스키마와 무결성으로 핵심 데이터를 신뢰 가능하게 다루는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 릴레이션 | 동일한 속성 구조를 가진 행 집합으로 업무 데이터를 논리적으로 표현함 |
| 키 | 기본키와 외래키로 개체 식별과 관계 연결과 중복 방지를 수행함 |
| 제약조건 | 도메인과 개체와 참조 무결성을 강제해 데이터 품질을 유지함 |
| SQL 엔진 | 선언형 질의와 갱신을 처리해 저장 구조와 사용 질의를 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스키마 정의     | --> | 데이터 저장     | --> | 질의/조인 수행  | --> | 무결성 유지     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스키마 정의**: 테이블과 키와 제약조건을 설계함
2. **데이터 저장**: 행 단위로 데이터를 삽입하고 갱신함
3. **질의와 조인 수행**: SQL로 조건 검색과 관계 조회를 처리함
4. **무결성 유지**: 제약과 트랜잭션으로 데이터 일관성을 보장함

## Ⅵ. 실무 적용 및 유의점

1. 금융 계정계와 주문 처리처럼 정합성이 중요한 시스템에서는 관계형 DB가 적합하지만 업무 규칙을 스키마에 반영하지 않으면 중복과 불일치가 쌓이므로 키와 제약조건 설계를 강화하고 무결성 위반 건수와 중복 데이터 비율로 확인함
2. 전자상거래와 SaaS 서비스에서는 데이터는 정합해도 질의 성능이 문제 될 수 있으므로 실제 작업 부하 기준으로 인덱스와 실행 계획을 점검하고 느린 질의 비율과 인덱스 활용률로 확인함

## Ⅶ. 결론

관계형 데이터베이스는 핵심 업무 데이터를 구조화된 스키마와 무결성과 트랜잭션으로 안정적으로 다뤄야 하는 환경에서 가장 강점을 보임.
