# 📖 【암기용】 개념 완전 이해

## 한눈에
- **페이징 (Paging)**: 메모리를 **기계적인 고정 크기**(Page)로 나누는 방식. 외부 단편화는 없지만, 마지막 페이지에 자투리 공간이 남는 **내부 단편화**가 발생함.
- **세그멘테이션 (Segmentation)**: 메모리를 **논리적인 의미 단위**(Code, Data, Stack 등)로 나누는 방식. 내부 단편화는 없지만, 할당과 해제를 반복하다 보면 사이사이에 못 쓰는 틈이 생기는 **외부 단편화**가 발생함.
- **혼용 기법 (Paged Segmentation)**: 세그먼트를 다시 페이지로 나누는 방식. 현대 OS가 채택하는 **가장 정교한 메모리 관리** 전략.

## 깊이 이해
- **단편화(Fragmentation)의 정체**:
    - **외부(External)**: 총 빈 공간은 충분한데, 조각나 있어서 큰 프로세스를 못 넣음.
    - **내부(Internal)**: 할당된 방 안에서 프로세스가 다 안 써서 남는 공간. (낭비)
- **페이징의 하이라이트**: 주소 변환이 단순함. `(페이지 번호, 변위)`만 알면 됨. 모든 페이지 크기가 같으니 빈자리 찾기도 쉬움.
- **세그멘테이션의 하이라이트**: '함수'나 '배열' 단위로 메모리를 나누니, "이 세그먼트는 읽기만 가능", "저 세그먼트는 실행 불가" 식의 **보호(Protection)**와 **공유(Sharing)**가 매우 직관적임.
- **Segmentation Fault**: 프로세스가 자신에게 할당되지 않은 세그먼트 주소를 찌를 때 OS가 내리는 사형 선고.

## 연결 개념
- **Virtual Memory (015)**: 페이징과 세그멘테이션을 통해 가상 공간을 구축함.
- **Memory Fragmentation**: 메모리 관리자가 평생 싸워야 할 적.
- **TLB (020)**: 페이징의 주소 변환 속도를 책임지는 파수꾼.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 하드웨어 효율성 중심의 **페이징(Paging)**과 사용자 논리 구조 중심의 **세그멘테이션(Segmentation)**을 통해 가상 주소 공간을 물리 메모리에 매핑하는 기법임.
> 2. **기술적 핵심**: 페이징은 **외부 단편화**를 제거하여 메모리 할당 효율을 높이고, 세그멘테이션은 **의미 단위의 보호와 공유**를 용이하게 함.
> 3. **진화**: 현대 OS는 세그멘테이션의 논리적 장점과 페이징의 관리적 장점을 결합한 **단일/다단계 페이징** 기반의 하이브리드 방식을 표준으로 사용함.

## Ⅰ. 가상 메모리 관리의 두 축, 페이징과 세그멘테이션 개요
- **페이징**: 가상 메모리를 고정된 크기의 블록(Page)으로 분할하여 비연속적인 물리 메모리(Frame)에 할당하는 방식.
- **세그멘테이션**: 가상 메모리를 논리적 의미 단위(Segment)로 분할하여 서로 다른 크기의 물리 메모리에 할당하는 방식.

## Ⅱ. 페이징과 세그멘테이션 비교 분석

### 1. 기술적 상세 비교
| 구분 | 페이징 (Paging) | 세그멘테이션 (Segmentation) |
|:---:|:---|:---|
| **분할 단위** | 고정 크기 (4KB, 2MB 등) | 가변 크기 (논리적 의미 단위) |
| **단편화 문제** | **내부 단편화** 발생 | **외부 단편화** 발생 |
| **매핑 정보** | Page Table | Segment Table |
| **주소 구성** | `(p, d)` : 페이지 번호, 변위 | `(s, d)` : 세그먼트 번호, 변위 |
| **관리 주체** | OS 커널 / 하드웨어 | 컴파일러 / 사용자 / OS |
| **주요 목적** | 물리 메모리 활용 극대화 | 보호(Protection) 및 공유(Sharing) |

### 2. 단편화(Fragmentation) 현상 비교
- **페이징**: 외부 단편화 완벽 해결. 하지만 마지막 페이지에 프로세스 크기만큼 할당 후 남는 **Internal Fragmentation** 존재.
- **세그멘테이션**: 내부 단편화 없음. 그러나 다양한 크기의 세그먼트 할당/해제 반복 시 사이사이에 빈 공간이 남는 **External Fragmentation** 심화.

## Ⅲ. 하이브리드 전략: Paged Segmentation

### 1. 개념 및 동작 원리
- 프로그램을 세그먼트 단위로 먼저 나누고, 각 세그먼트를 다시 고정 크기의 페이지로 분할하여 관리.
- **주소 변환**: `(s, p, d)` -> 세그먼트 번호(s)로 세그먼트 테이블 참조 -> 해당 세그먼트의 페이지 테이블(p) 참조 -> 물리 프레임 주소 + 변위(d).

### 2. 기술적 가치
- 세그멘테이션의 **논리적 보호/공유** 기능 유지.
- 페이징의 **외부 단편화 해결** 및 물리 메모리 할당 편의성 확보.

## Ⅳ. 현대 OS의 주소 변환 고속화 기술

- **다단계 페이지 테이블 (Multi-level Paging)**: 64비트 광대한 가상 공간을 관리하기 위해 페이지 테이블을 계층화하여 메모리 낭비 방지.
- **TLB (Translation Lookaside Buffer)**: 빈번히 참조되는 페이지 테이블 항목을 CPU 내부 캐시에 저장하여 변환 속도 극대화.
- **Inverted Page Table**: 프로세스별 테이블 대신 물리 프레임당 하나의 항목만 두어 테이블 크기를 획기적으로 줄임.

## Ⅴ. 기술적 심화: 메모리 보호와 공유

1. **보호 (Protection)**: 세그먼트 테이블에 Read/Write/Execute 비트를 설정하여 불법적인 메모리 접근(Segment Violation) 원천 차단.
2. **공유 (Sharing)**: 여러 프로세스의 페이지/세그먼트 테이블 항목이 동일한 물리 메모리 프레임을 가리키게 하여 라이브러리 중복 로드 방지.

## Ⅵ. 기술사 관점의 결론 및 제언
- 페이징과 세그멘테이션의 선택은 **'메모리 활용률'과 '관리 편의성'**의 트레이드오프 결과임.
- **실무 제언**: 고성능 시스템 설계 시, 페이지 크기를 키워 TLB 미스를 줄이는 **Huge Pages** 설정이나, 메모리 집약적 작업 시 단편화를 최소화하는 **SLAB/Buddy System** 할당자의 특성을 이해하고 튜닝해야 함.
