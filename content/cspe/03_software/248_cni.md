## Ⅰ. 개요
- 정의: 컨테이너 간의 통신을 위해 네트워크 자원을 설정하고 해제하는 표준 명세임
- 배경: 다양한 네트워크 솔루션과 컨테이너 오케스트레이터 간의 호환성 확보 필요
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| CNI 플러그인 | Calico, Flannel, Cilium | 매우높음 |
| 구현 방식 | Overlay, L3 Routing | 높음 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ Container ] <--- veth ---> [ Bridge ] <--- eth0 ---> [ Physical NW ]
       ^                          |
       +------- ( CNI Plugin ) ---+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| veth pair | 컨테이너 내부와 호스트를 연결하는 가상 케이블 | 랜선 |
| Overlay NW | 물리 네트워크 위에 구축되는 가상 논리 네트워크 | 터널 |
| IPAM | 컨테이너에 IP 주소를 할당하고 관리하는 모듈 | 주소 부여소 |

> 요약: CNI 플러그인이 veth·IP 주소·라우팅을 설정하여 컨테이너 네임스페이스를 네트워크에 연결함

## Ⅲ. 절차
- ASCII 흐름도
  [컨테이너 생성] -> [CNI 바이너리 호출] -> [네트워크 설정] -> [연결 완료]
     (Kubelet)         (Add Command)       (IP할당/Route)     (Traffic통로)

- 4단계 설명
1. 호출준비: 런타임이 컨테이너의 네트워크 네임스페이스를 생성함
2. 설정요청: CNI 구성 파일에 따라 해당 플러그인(바이너리)을 실행함
3. 자원할당: IPAM을 통해 IP를 할당하고 인터페이스를 생성하여 연결함
4. 라우팅구성: 호스트 간 통신을 위해 라우팅 테이블을 업데이트하거나 터널 생성함

> 요약: 인터페이스 표준을 통해 네트워크 설정 과정을 자동화 및 모듈화함

## Ⅳ. 문제점
- Overlay 네트워크 사용 시 캡슐화(Encapsulation)에 따른 성능 저하 발생함
- 복잡한 마이크로서비스 환경에서 네트워크 가시성 확보 및 디버깅이 어려움

## Ⅴ. 개선방안
- (단기) eBPF 기반 CNI를 적용하고 처리 지연·CPU 사용률·정책 기능을 기존 방식과 비교함
- (중기) BGP 기반의 L3 라우팅(Calico 등)을 적용하여 캡슐화 오버헤드 제거함
- (장기) 서비스 메시(Service Mesh)와 연계하여 세밀한 트래픽 제어 및 가시성 확보함

## Ⅵ. 전망
- 멀티 클라우드 환경을 지원하는 클러스터 간(Multi-cluster) 네트워킹 중요해짐
- 5G/6G 환경의 초저지연 통신을 위한 하드웨어 가속 기반 CNI 도입 예상됨
