## Ⅰ. 개요
- 정의: 페이지 테이블 크기를 줄이기 위해 트리 구조(다단계)나 해시 구조(역)를 사용하는 기법
- 배경: 64비트 등 광활한 주소 공간에서 선형 페이지 테이블 유지 시 메모리 낭비 심각
- 출제 의도: 대용량 주소 체계에서의 효율적인 테이블 관리 기법과 탐색 오버헤드 이해

## Ⅱ. 구성요소
```
[ Multilevel ]                 [ Inverted ]
Outer -> Inner -> Page         PID + PageNum -> Hash Func
(Hierarchical Tree)            (Frame Index Search)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 다단계 페이징 | 테이블을 쪼개어 필요한 부분만 메모리에 적재 | 백과사전 목차 |
| 역 페이징 | 물리 프레임당 하나의 엔트리만 유지 (PID 포함) | 좌석 기준 명부 |
| TLB | 주소 변환 속도를 높이기 위한 고속 캐시 메모리 | 요약 주소록 |
> 요약: 다단계는 공간 절약을 위해 계층화하고, 역 페이징은 전체 크기를 고정함.

## Ⅲ. 절차
```
[Logical Addr] -> [Multi-index Look-up] -> [Frame Found] -> [Access]
[Logical Addr] -> [Hash(PID+P)] -> [Match Entry] -> [Frame Found]
```
1. (다단계) 논리 주소의 비트를 분할하여 상위/하위 테이블을 순차적으로 탐색함
2. (역) PID와 페이지 번호를 조합하여 해시 함수를 통해 테이블 인덱스 추출
3. 탐색 성공 시 해당 프레임 번호를 획득하여 물리 주소로 변환
4. 실패 시 페이지 폴트 처리 또는 체이닝(Chaining)을 통한 추가 탐색 수행
> 요약: 간접 참조(다단계) 또는 검색(역)을 통해 메모리 맵핑을 실현함.

## Ⅳ. 문제점
- 원인: 다단계 페이징은 단계가 깊어질수록 메모리 접근 횟수가 늘어나 지연 시간 증가함
- 원인: 역 페이징은 공유 메모리(Shared Memory) 구현 시 주소 맵핑이 복잡해지는 한계

## Ⅴ. 개선방안
- (단기) TLB(Translation Lookaside Buffer) 적중률을 높여 메모리 접근 횟수 최소화
- (중기) 해시 충돌 방지를 위한 최적의 해시 함수 설계 및 체이닝 길이 관리
- (장기) 하드웨어적 지원을 강화한 섀도우 페이지 테이블 또는 확장 페이지 테이블(EPT) 활용

## Ⅵ. 전망
- 가상화 기술(KVM, VMware)의 확산으로 중첩된 주소 변환(Nested Paging) 성능이 핵심 경쟁력임
- 비휘발성 대용량 메모리 시대에 대응하는 새로운 계층 구조의 주소 변환 아키텍처 연구 지속됨
