## Ⅰ. 개요
- 정의: 미리 일정 수의 스레드를 생성하여 대기시키고, 작업 요청 시 재사용하는 관리 기법
- 배경: 빈번한 스레드 생성/제거에 따른 시스템 오버헤드 방지 및 자원 사용량 제한 필요
- 출제 의도: 스레드 생성 비용, 큐 대기, 풀 크기 조정 기준의 이해 여부

## Ⅱ. 구성요소
```
[ Client ] -> [ Task Queue ] -> [ Thread Pool ]
                 (FIFO)        | T1 | T2 | T3 |
                               | T4 | T5 | T6 |
```
| 구성요소 | 설명 | 관리 기준 |
| :--- | :--- | :--- |
| 작업 큐 | 실행 대기 중인 Task들을 저장하는 버퍼 | 큐 길이와 대기 시간 |
| 워커 스레드 | 풀 내에서 루프를 돌며 작업을 꺼내 실행하는 스레드 | 활성·유휴 스레드 수 |
| 풀 관리자 | 스레드 개수를 동적으로 조절하고 상태를 감시하는 로직 | 코어·최대 풀 크기 |
> 요약: 작업 큐와 유휴 스레드 집합을 결합하여 동시성을 제어함.

## Ⅲ. 절차
```
[Request] -> [Queue Submit] -> [Worker Pick] -> [Execute] -> [Idle Return]
```
1. 애플리케이션이 스레드 풀에 작업 실행을 요청(Submit)함
2. 요청된 작업은 작업 큐에 담기고, 유휴(Idle) 상태인 워커 스레드가 이를 감지
3. 워커 스레드가 큐에서 작업을 꺼내어 로직을 수행함
4. 작업 완료 후 스레드는 소멸하지 않고 다시 풀로 돌아가 다음 작업 대기
> 요약: 스레드 재사용으로 생성 비용과 큐 대기 시간을 함께 줄임.

## Ⅳ. 문제점
- 원인: 너무 작은 풀 크기는 병목을 초래하고, 너무 크면 메모리 낭비 및 스위칭 부하 발생
- 원인: 오래 걸리는 작업이 워커를 점유하면 뒤 작업의 큐 대기 시간이 길어짐

## Ⅴ. 개선방안
- (단기) 워크로드 특성(CPU/IO Bound)에 맞춘 적정 코어 스레드 수 산정
- (중기) 워크 스틸링(Work Stealing) 기법 도입으로 스레드 간 부하 불균형 해소
- (장기) 서버리스 등 동적 환경을 위한 자동 스케일링(Auto-scaling) 스레드 풀 적용

## Ⅵ. 전망
- 가상 스레드(Project Loom 등) 기술과 결합하면 요청당 실행 단위 비용을 낮추는 구조로 확장됨
- 클라우드 네이티브 환경에서는 큐 길이와 처리 지연을 기준으로 풀 크기와 인스턴스 수를 함께 조정함

## 작성 근거(검토용)

- 스레드 풀은 추상 성능어보다 생성 비용, 큐 대기, 활성·유휴 스레드 수, 풀 크기 기준으로 설명해야 함
- 끝없는 대기 단정을 제거하고 오래 걸리는 작업이 워커를 점유해 큐 대기 시간이 길어지는 조건으로 고침
