## 미리 알고가기

- 비동기 I/O는 요청 후 즉시 제어를 반환하고 완료 시점에 통지받는 방식임
- 이벤트 루프는 준비된 이벤트를 순차적으로 처리하는 실행 구조임
- 핵심은 적은 스레드로 많은 연결을 효율적으로 처리하는 것임

## Ⅰ. 개요

- **정의/개념**: 비동기 I/O와 이벤트 루프는 입출력 완료를 기다리는 동안 스레드를 묶어두지 않고, 준비된 이벤트만 선택적으로 처리해 적은 실행 자원으로 많은 연결과 요청을 처리하는 서버 실행 모델임
- **배경/필요성**: 전통적인 thread-per-connection 방식은 연결 수가 많아지면 문맥 전환과 메모리 사용량이 급증하므로, 대규모 네트워크 서버에는 비동기 기반 실행 구조가 필요함

## Ⅱ. 특징

- 적은 수의 스레드로 많은 I/O 대기 작업을 다룰 수 있음
- backpressure와 callback 흐름을 설계하지 않으면 복잡도가 급증함
- CPU 집약 작업은 이벤트 루프에서 분리해야 응답성을 유지할 수 있음
- tail latency는 이벤트 큐 길이와 작업 편차에 민감함

## Ⅲ. 종류 및 비교

| 판단 기준 | 동기식 I/O | 비동기 I/O 이벤트 루프 |
|:---|:---|:---|
| 스레드 사용 | 연결 수 비례 증가 | 적은 스레드 유지 가능 |
| 코드 흐름 | 직선적 | 콜백 또는 future 중심 |
| 장점 | 이해와 디버깅 쉬움 | 고동시성 처리 효율 높음 |
| 주의점 | 자원 비용 큼 | 복잡도와 backpressure 설계 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Event Loop | 준비된 이벤트를 가져와 순차 실행해 전체 응답성과 공정성을 결정함 |
| Non-blocking I/O API | read와 write가 즉시 반환되도록 해 스레드 낭비를 줄임 |
| Callback or Future Chain | 완료 시 후속 처리를 연결해 비동기 흐름을 구성함 |
| Worker Pool | CPU 집약 작업을 이벤트 루프 밖으로 분리해 루프 지연을 막음 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요청 등록      | --> | 이벤트 감시    | --> | 준비 이벤트 처리 | --> | 완료 통지      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요청 등록**: 소켓이나 파일 I/O 작업을 non-blocking 방식으로 등록함
2. **이벤트 감시**: selector나 poller가 준비된 이벤트를 기다림
3. **준비 이벤트 처리**: 읽기와 쓰기와 완료 콜백을 실행함
4. **완료 통지**: 결과를 후속 로직에 전달하고 다음 작업을 연결함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 이벤트 루프 안에서 느린 연산이 실행되면 전체 연결의 응답성이 동시에 악화될 수 있음
   - 해결방안: CPU bound 작업을 별도 worker pool로 분리하고 event loop lag와 p99 latency로 검증함
2. 문제: 비동기 체인이 복잡해지면 오류 전파와 자원 해제가 누락되기 쉬움
   - 해결방안: 구조화된 future 패턴과 공통 에러 핸들러를 적용하고 callback failure rate와 leak count로 검증함
3. 문제: backpressure 없이 입력만 늘어나면 큐가 폭증해 메모리 사용량과 tail latency가 급등할 수 있음
   - 해결방안: admission control과 queue bound를 적용하고 queue depth와 drop rate로 검증함

## Ⅶ. 적용 사례

- 고동시성 API 서버에서는 이벤트 루프 기반 네트워크 처리를 사용하고, event loop lag와 p99 latency로 결과를 확인함
- 실시간 메시지 게이트웨이에서는 non-blocking 소켓을 적용하고, queue depth와 drop rate로 결과를 확인함
- 비동기 배치 파이프라인에서는 future 체인을 표준화하고, callback failure rate와 throughput stability로 결과를 확인함

## Ⅷ. 결론

비동기 I/O와 이벤트 루프의 핵심은 많은 연결을 빠르게 처리하는 것이 아니라 느린 작업과 큐 폭증을 통제하며 응답성을 유지하는 데 있음.
