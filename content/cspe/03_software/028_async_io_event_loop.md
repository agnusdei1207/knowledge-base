## 핵심 인사이트 (3줄 요약)
- I/O 작업의 완료를 기다리지 않는 Non-Blocking 방식과, 완료된 이벤트를 큐에서 꺼내 단일 스레드로 처리하는 동시성 모델.
- 수만 개의 동시 커넥션(C10K 문제) 상황에서도 스레드 컨텍스트 스위칭 오버헤드와 메모리 고갈을 원천 차단함.
- Nginx, Node.js, Redis 등 고성능 소프트웨어의 뼈대 기술로, CPU 바운드 작업의 오프로딩(Off-loading) 설계가 성패를 좌우함.

## Ⅰ. 개요 및 필요성
- **개요**: OS 커널의 다중화 I/$O(epoll, kqueue)$ 기능과 사용자 레벨의 이벤트 디스패처가 결합되어 동작하는 논블로킹 아키텍처.
- **필요성**: 기존의 Thread-per-Connection 방식은 동시 접속자가 늘어나면 1MB씩 할당되는 스택 메모리 때문에 OOM(Out of Memory)이 발생하고 CPU는 컨텍스트 스위칭만 하다 뻗는 현상이 발생함. 최소 자원으로 최대의 동시성을 감당할 구조가 필요했음.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **동작 방식**:
  1. 어플리케이션은 OS에게 비동기 I/O를 요청하고 제어권을 바로 반환받음.
  2. 커널(Event Demultiplexer)이 I/O 완료를 감지하여 Event Queue에 콜백을 넣음.
  3. 단일 스레드로 도는 Event Loop가 Call Stack이 비어있을 때마다 Queue에서 작업을 꺼내 실행함.

```text
+---------------------+    (3) Enqueue     +-------------------+
|  OS Kernel (epoll/  | -----------------> |    Event Queue    |
|  kqueue/io_uring)   |                    | (Micro/Macro Task)|
+---------------------+                    +-------------------+
        ^                                            |
        | (1) Async I/O Request                      | (4) Dequeue & Execute
        |                                            v
+---------------------+    (2) Return      +-------------------+
|   User Program      | <----------------- |   Event Loop      |
|   (Call Stack)      |   (Non-Blocking)   |   (Single Thread) |
+---------------------+                    +-------------------+
```

## Ⅲ. 비교 및 연결
| 구분 | 멀티 스레드 모델 (Apache MPM) | 이벤트 루프 모델 (Nginx, Node.js) |
|---|---|---|
| **처리 방식** | 커넥션당 1개 스레드 생성/할당 | 1개 스레드가 다수 커넥션 멀티플렉싱 |
| **I/O 대기 상태** | Blocking (스레드가 멈춰서 기다림) | Non-Blocking (다른 이벤트 지속 처리) |
| **메모리 풋프린트** | 매우 큼 (동시성 증가 시 기하급수적 증가) | 극히 적음 (이벤트 큐 크기 정도만 증가) |
| **치명적 약점** | C10K 이상의 접속 시 서버 다운 | 단일 스레드 내 CPU 연산 집약 시 루프 전체 마비 |

## Ⅳ. 실무 적용 및 기술사 판단
- **Event Loop Blocked 한계 극복**: 이벤트 루프 안에서 암호화, 이미지 리사이징, 거대 JSON 파싱 등 무거운 CPU 연산을 수행하면 대기 중인 모든 요청이 멈춤(Starvation). 이를 피하기 위해 Worker Thread Pool에 넘기는 Off-loading 아키텍처가 필수적임.
- **최신 커널 트렌드 적용**: 리눅스 커널 5.1 이후 도입된 `io_uring`을 적용하면 시스템 콜 오버헤드마저 없앨 수 있어 차세대 비동기 I/O 표준으로 자리 잡는 중.
---
## Ⅴ. 기대효과 및 결론
- 이벤트 루프 모델은 API Gateway, 채팅 서버(WebSocket), 스트리밍 등 I/O가 잦고 대규모 접속이 발생하는 도메인에서 압도적인 가성비를 제공함.
- 결론적으로, 비동기 논블로킹 패러다임은 클라우드 네이티브 환경의 리소스 최적화에 기여하며, 향후 Virtual Thread와의 하이브리드 조합으로 발전해 나갈 것임.
