## Ⅰ. 개요
- 정의: 여러 개의 하드 디스크를 하나의 논리적 단위로 묶어 성능과 신뢰성을 높이는 기술
- 배경: 단일 디스크의 성능 한계 극복 및 예기치 못한 하드웨어 장애로부터 데이터 보호 필요
- 출제 의도: 레벨별 데이터 분산(Striping)과 복제(Mirroring), 패리티(Parity)의 메커니즘 이해

## Ⅱ. 구성요소
```
[ RAID 0: Striping ]    [ RAID 1: Mirroring ]    [ RAID 5: Parity ]
+------+------+         +------+------+          +------+------+------+
| D1-A | D2-A |         | D1-A | D2-A |          | D1-A | D2-B | D3-P |
+------+------+         +------+------+          +------+------+------+
| D1-B | D2-B |         | D1-B | D2-B |          | D1-C | D2-P | D3-D |
+------+------+         +------+------+          +------+------+------+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 스트라이핑 | 데이터를 여러 디스크에 분산 저장하여 병렬성 확보 | 분업화 |
| 미러링 | 동일한 데이터를 다른 디스크에 복제하여 결함 허용 | 예비 부품 |
| 패리티 | 데이터 복구를 위한 연산값(XOR)을 계산하여 저장 | 정답지 |
> 요약: 성능(0), 안정성(1), 효율(5/6)의 균형점에 따라 레벨을 선택함.

## Ⅲ. 절차
```
[Data Write] -> [XOR Calc (if RAID 5)] -> [Striping/Mirroring] -> [Disk Commit]
```
1. 호스트의 데이터 쓰기 요청 발생 시 컨트롤러가 대상 디스크 그룹 결정
2. RAID 5/6의 경우 기록할 데이터 블록들을 XOR 연산하여 패리티 정보 생성
3. 정해진 레벨 정책에 따라 복제하거나 스트라이핑하여 각 물리 디스크에 배분
4. 특정 디스크 장애 시 남은 데이터와 패리티를 이용해 누락된 정보 복원(Rebuild)
> 요약: 중복과 연산을 통해 가용성을 유지하며 데이터를 기록함.

## Ⅳ. 문제점
- 원인: RAID 0은 단 하나만 고장 나도 전체 데이터 손실되는 높은 취약성 가짐
- 원인: RAID 5는 쓰기 시 패리티 갱신 오버헤드(Write Penalty)로 성능 저하 발생 가능

## Ⅴ. 개선방안
- (단기) 핫 스페어(Hot Spare) 디스크를 상시 배치하여 장애 시 즉각 자동 복구 수행
- (중기) RAID 10(1+0)과 같이 성능과 안정성을 모두 잡은 복합 레벨 적용
- (장기) 소프트웨어 정의 스토리지(SDS) 및 Erasure Coding 기법 도입으로 효율 극대화

## Ⅵ. 전망
- 대용량 HDD의 복구 시간 증대에 따라 2개 디스크 장애를 견디는 RAID 6의 비중 확대
- SSD 전용 RAID 컨트롤러 기술 발전으로 가비지 컬렉션 부하를 고려한 수명 최적화 기술 도입
