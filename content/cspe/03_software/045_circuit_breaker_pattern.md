## 미리 알고가기

- 서킷 브레이커는 실패가 누적될 때 하위 호출을 일시 차단하는 회복성 패턴임
- closed와 open과 half-open 상태 전이가 핵심 구조임
- 목적은 실패 서비스 보호보다 상위 서비스 전파 장애를 막는 것임

## Ⅰ. 개요

- **정의/개념**: 서킷 브레이커 패턴은 외부 서비스 호출 실패가 일정 기준을 넘으면 하위 호출을 일시 차단하고, 일정 시간이 지난 뒤 제한적으로 재시도해 분산 시스템의 장애 전파를 줄이는 회복성 제어 패턴임
- **배경/필요성**: 분산 환경에서는 느린 하위 서비스 하나가 스레드 고갈과 재시도 폭증을 일으켜 전체 장애로 번질 수 있으므로, 실패를 빠르게 차단하고 복구를 신중하게 확인하는 보호 장치가 필요함

## Ⅱ. 특징

- 장애 서비스로 가는 불필요한 호출을 줄여 자원 고갈을 막음
- 상태 전이 기반으로 장애와 복구를 제어함
- timeout과 bulkhead와 fallback과 함께 써야 효과가 큼
- 임계치가 부정확하면 정상 서비스도 과도하게 차단할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 재시도 | 서킷 브레이커 |
|:---|:---|:---|
| 실패 대응 | 계속 재시도 | 일정 실패 후 차단 |
| 장점 | 일시 오류 복구 가능 | 장애 전파와 자원 고갈 방지 |
| 한계 | 장애 시 폭주 가능 | 튜닝 실패 시 과차단 가능 |
| 적합 환경 | 짧은 일시 오류 | 분산 서비스 보호 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Failure Counter | 오류율과 timeout 수를 집계해 차단 여부 판단의 기준을 제공함 |
| State Machine | closed와 open과 half-open 상태를 관리해 호출 허용과 차단을 결정함 |
| Fallback Logic | 차단 중에도 기본 응답이나 대체 흐름을 제공해 사용자 영향 범위를 줄임 |
| Recovery Probe | half-open 상태에서 제한된 요청만 통과시켜 실제 복구 여부를 검증함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 호출 시도      | --> | 실패율 판단    | --> | 차단 또는 통과  | --> | 복구 재확인    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **호출 시도**: 상위 서비스가 하위 서비스 호출을 시작함
2. **실패율 판단**: timeout과 오류 횟수를 누적해 임계치를 확인함
3. **차단 또는 통과**: 정상 시 통과하고 임계 초과 시 open 상태로 차단함
4. **복구 재확인**: 일정 시간 후 half-open으로 제한 호출을 보내 상태를 점검함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 임계치와 복구 대기 시간이 실제 트래픽 특성과 맞지 않으면 정상 구간에서도 과도 차단이 발생할 수 있음
   - 해결방안: 서비스별 실패 기준을 분리하고 false open rate와 protection hit rate로 검증함
2. 문제: 서킷 브레이커만 두고 timeout과 bulkhead를 함께 설계하지 않으면 스레드 고갈을 충분히 막지 못할 수 있음
   - 해결방안: timeout과 격리 정책을 결합하고 thread pool saturation과 timeout effectiveness로 검증함
3. 문제: fallback 응답이 업무 의미와 맞지 않으면 장애는 줄여도 잘못된 결과를 사용자에게 줄 수 있음
   - 해결방안: fallback 정책을 도메인별로 정의하고 fallback correctness rate와 user impact severity로 검증함

## Ⅶ. 적용 사례

- 결제 연동 서비스에서는 서킷 브레이커를 적용하고 확인 지표는 protection hit rate와 thread pool saturation임
- 외부 API 집계 서비스에서는 fallback 응답을 설계하고 확인 지표는 false open rate와 fallback correctness rate임
- 서비스 메시 환경에서는 timeout과 차단을 함께 설정하고 확인 지표는 timeout effectiveness와 user impact severity임

## Ⅷ. 결론

서킷 브레이커의 목적은 실패를 숨기는 것이 아니라 장애 전파를 끊고 복구 확인을 통제해 상위 시스템 생존성을 확보하는 데 있음.
