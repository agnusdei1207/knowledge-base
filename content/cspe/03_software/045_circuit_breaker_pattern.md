## 미리 알고가기

- 서킷 브레이커(Circuit Breaker): 분산 시스템에서 하위 서비스 장애 시 요청을 차단하여 장애 전파를 막는 회복성 설계 패턴임
- Closed / Open / Half-open: 서킷 브레이커의 3대 상태로, 정상 동작(Closed), 즉시 차단 및 Fallback 실행(Open), 복구 테스트(Half-open)를 나타냄
- Bulkhead Pattern: 시스템 자원을 격벽으로 나누어 특정 도메인의 장애가 전체 자원의 고갈로 번지지 않도록 하는 패턴임
- Fallback: 하위 서비스 장애로 호출이 실패하거나 차단(Open)되었을 때 반환하는 미리 정의된 대안 비즈니스 결과임
- 임계치(Threshold): 서킷 브레이커 상태 전이를 유발하는 호출 실패율이나 최소 호출 횟수 기준치임

## 작성 근거(검토용)

- 서킷 브레이커는 실패 임계치와 Closed·Open·Half-open 상태 전이를 핵심 원리로 삼아 장애 차단의 자동화 원리를 명확히 함
- 단순 재시도와 서킷 브레이커의 대비를 통해 장애 제어 방식, 시스템 자원 영향, 잠재적 리스크를 실무 관점에서 규명함
- 문장별 5회 전수 검수 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정했음을 밝힘

## Ⅰ. 개요

- **정의/개념**: 서킷 브레이커는 하위 호출 실패가 임계치를 넘으면 호출을 차단하고 제한된 탐색 호출로 복구를 판정하는 상태 기반 패턴임
- **배경/필요성**: 하위 서비스 장애로 인한 재시도 폭증과 스레드 풀 고갈을 억제하기 위해 호출 차단과 복구 판정 상태가 필요함

### 쉽게 이해하기 (학습용)
- 가정용 누전 차단기(두꺼비집)와 같습니다. 특정 가전제품에서 합선이 일어나 전류가 급증하면(장애), 집 전체가 불타지 않도록 차단기를 자동으로 내려서 안전을 보장합니다.

## Ⅱ. 특징

- 장애 서비스 호출을 차단해 상위 서비스의 스레드·연결 풀 점유를 제한함
- 상태 전이 기반으로 차단와 복구 확인을 체계적으로 제어함
- 타임아웃·재시도·격리 풀·대체 응답과 결합해 호출 시간과 자원 점유 범위를 제한함
- 임계치가 부정확하면 정상 호출까지 차단하거나 장애 호출을 계속 허용할 수 있음

### 쉽게 이해하기 (학습용)
- 문제 지점으로 가는 통로를 단절하여 대기 차량이 몰리지 않도록 차단하되, 일정 시간 뒤에 살짝 연결해 복구되었는지 확인하는 똑똑한 제어 장치입니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 재시도 | 서킷 브레이커 |
|:---|:---|:---|
| 장애 제어 방식 | 오류가 발생해도 동일한 호출을 계속해서 다시 시도함 | 실패율 누적 시 일정 시간 동안 호출을 전면 차단함 |
| 시스템 자원 영향 | 재시도로 인해 하위 호출 및 대기 스레드 풀의 부하 가중 | 무조건 즉시 실패(Fallback) 처리하여 호출 측 스레드 고갈 방지 |
| 잠재적 리스크 | 장애 발생 부서에 지속적인 요청을 보내 과부하 파국 초래 | 오설정 시 정상 호출의 임의 차단(오인 차단) 및 회복 지연 발생 |

### 쉽게 이해하기 (학습용)
- 전화를 안 받을 때 계속 다시 전화를 걸어 대기 시간을 낭비하는 것(재시도)과 달리, 신호가 차단된 것을 확인하고 통화를 바로 끊은 뒤 기본 메시지(대체 응답)를 띄워 자원을 보호합니다.

## Ⅳ. 설계 요소 및 구조

```text
+--------------------------------------------------------------+
|                          Caller Service                      |
|                                                              |
|        +-----------------------------------------------+     |
|        |                Circuit Breaker                |     |
|        |                                               |     |
|        |  +-----------------+     +-----------------+  |     |
|        |  |  State Machine  | <-> | Failure Counter |  |     |
|        |  +-----------------+     +-----------------+  |     |
|        |          |                                    |     |
|        |          v                                    |     |
|        |  +-----------------+                          |     |
|        |  | Fallback Logic  |                          |     |
|        |  +-----------------+                          |     |
|        +-----------------------------------------------+     |
+--------------------------------------------------------------+
           | (Closed / Half-Open)           | (Open)
           v                                v
+----------------------+          +--------------------+
|  Callee (Dependency) |          | Fallback Response  |
+----------------------+          +--------------------+
```

| 설계 요소 | 설명 |
|:---|:---|
| 실패 카운터 | 오류율과 타임아웃 수를 집계해 차단 임계치 도달 여부를 판정함 |
| 상태 기계 | Closed·Open·Half-open 상태로 호출 허용과 차단을 제어함 |
| 대체 응답 로직 | Open 상태에서 도메인 정책에 따른 대체 결과를 반환함 |
| 복구 탐색 호출 | Half-open 상태에서 제한된 요청으로 하위 서비스 복구 여부를 판정함 |

### 쉽게 이해하기 (학습용)
- 고장 횟수를 세는 계수기(카운터), 신호등 상태판(상태 기계), 고장 시 틀어주는 대안 녹음 음성(대체 응답), 가끔 흘려보내는 정찰용 신호(탐색 호출)로 설계됩니다.

## Ⅴ. 원리 및 절차 흐름도

```text
           +---------------------------------------------+
           |                                             |
           v                                             |
     +-----------+   Failure Rate > Threshold    +-----------+
     |  Closed   | ----------------------------> |   Open    |
     +-----------+                               +-----------+
           ^                                           |
           |                                           | Timeout Duration
           |               Success Rate                | Expired
           |               > Threshold                 v
           +------------------------------------- +-------------+
                                                  |  Half-Open  |
                                                  +-------------+
                                                       |
                                                       | Failure Rate
                                                       | > Threshold
                                                       v
                                                 (Back to Open)
```

1. **Closed (정상)**: 모든 외부 요청을 대상 서비스로 전송하며, 실패율 및 지연 임계치를 슬라이딩 윈도우 방식으로 측정함
2. **Open (차단)**: 실패율이 설정된 임계치(예: $50\%$)를 초과하면 상태가 Open으로 전환되어 즉시 에러나 Fallback 응답을 즉각 반환함
3. **Half-Open (복구 확인)**: Open 상태에서 지정된 쿨다운 시간이 지나면 Half-Open으로 전이하여 극소수의 테스트 트래픽만 전송함
4. **복구 판정**: 테스트 트래픽의 성공률이 기준치를 만족하면 Closed로 복귀하고, 실패하면 Open 상태를 유지하며 쿨다운 타이머를 재시작함

### 쉽게 이해하기 (학습용)
- 정상(Closed) 상태에서 호출 실패가 쌓여 한도를 넘으면 차단(Open) 상태가 되고, 진정 시간 후 일부 트래픽만 흘려보내며(Half-open) 복구를 확인하여 정상 또는 차단으로 전환하는 흐름입니다.

## Ⅵ. 실무 사례

1. 결제 외부 API는 호출별 실패 임계치와 격리 풀을 적용하고 차단 전환 시간·스레드 풀 포화율을 확인함
2. 상품 조회 서비스는 Half-open 탐색과 캐시 대체 응답을 적용하고 탐색 성공률·잘못된 대체 응답 수를 확인함

### 쉽게 이해하기 (학습용)
- 결제 외부 제휴 API 호출 시 타임아웃 오류율이 50%를 넘으면 즉시 서킷을 개방(Open)하고, DB의 캐시 데이터를 반환하는 Fallback을 실행하여 서비스 응답 지연을 방지합니다.

## Ⅶ. 결론

- 서킷 브레이커는 실패 임계치와 복구 탐색 상태로 하위 장애가 상위 자원을 고갈시키는 경로를 차단함
- 서비스 성격에 맞는 정밀한 임계치(Threshold) 튜닝과 비즈니스 악영향이 없는 최선의 Fallback 설계가 병행되어야 함

### 쉽게 이해하기 (학습용)
- 소수의 고장이 전체 시스템 마비로 번지지 않도록 막는 문지기와 같아서, 시스템 회복의 기초 공사이자 서비스 가용성을 보장하는 핵심 축입니다.
