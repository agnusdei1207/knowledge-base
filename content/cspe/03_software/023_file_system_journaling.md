# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 데이터를 쓰기 전에 변경될 내용을 별도의 로그 영역(**Journal**)에 미리 기록하여, 갑작스러운 전원 차단이나 시스템 충돌 시에도 **데이터의 무결성을 빠르게 복구**하는 기술.
- **핵심 직관**: 은행원의 장부 기록법. 돈을 주기 전(데이터 쓰기)에 "누구에게 얼마를 줄 것임"이라고 메모(저널링)를 먼저 함. 만약 메모 중 정전이 되면 없던 일로 하고, 메모 후 정전이 되면 메모를 보고 돈을 정확히 전달함.
- **왜 필요한가**: 저널링이 없으면 부팅 시 디스크 전체를 검사(FSCK)해야 해서 수 시간이 걸릴 수 있음. 저널링은 로그만 확인하면 되므로 수 초 내에 끝남.

## 깊이 이해
- **작동 원리 (Write-Ahead Logging)**:
    1. **Journal Write**: 변경될 메타데이터/데이터를 저널 영역에 씀.
    2. **Checkpoint**: 실제 파일 시스템 영역에 데이터를 씀.
    3. **Commit**: 기록이 완료되면 저널 내용을 지움.
- **저널링 모드**:
    - **Metadata Only (Ordered)**: 파일 위치, 크기 같은 정보만 저널링함. (성능 좋음, 파일 내용은 깨질 수 있음)
    - **Full Journaling (Data)**: 파일 내용까지 전부 저널링함. (가장 안전, 성능은 절반으로 뚝 떨어짐)
- **가치**: 고가용성(High Availability) 서버의 필수 요건. 시스템 신뢰성(Reliability)의 핵심.

## 연결 개념
- **File System (022)**: 저널링 기능을 내장한 현대 파일 시스템(NTFS, ext4).
- **ACID (095)**: 데이터베이스의 원자성과 영속성을 보장하는 저널링의 철학적 배경.
- **Consistency Check (FSCK)**: 저널링이 없던 시절의 느린 복구 방식.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 시스템 충돌 시 파일 시스템의 **일관성(Consistency)**을 보장하기 위해 변경 사항을 선기록(Write-Ahead Logging)하는 장애 복구 메커니즘임.
> 2. **기술적 핵심**: 메타데이터와 실데이터의 저널링 범위를 조절하여 **성능과 안전성 사이의 트레이드오프**를 최적화하며, 부팅 시 FSCK 오버헤드를 획기적으로 단축함.
> 3. **가치**: 예기치 못한 전원 장애 시 데이터 소실을 방지하고 시스템 가용시간(Uptime)을 극대화하는 엔터프라이즈 스토리지의 표준 기술임.

## Ⅰ. 시스템 신뢰성의 수호자, 파일 시스템 저널링의 개요
- **정의**: 파일 시스템의 메타데이터나 데이터를 변경하기 전에 해당 내용을 로그(Journal) 영역에 우선 기록하여 일관성을 유지하는 기법.
- **필요성**: 비정상 종료 시 무결성 보장, 복구 시간(RTO) 단축, 디스크 전체 스캔 방지.

## Ⅱ. 저널링의 동작 메커니즘: 3단계 Commit 프로세스

### 1. 처리 흐름도
```text
[요청] ──▶ [1. Journal Write] ──▶ [2. Checkpoint] ──▶ [3. Commit/Purge]
            (로그 영역에 선기록)      (실제 디스크 반영)     (로그 삭제/완료)
```

### 2. 복구 과정 (Recovery)
- **Replay**: 저널에 기록은 끝났으나 체크포인트가 안 된 작업을 마저 실행 (Redo).
- **Discard**: 저널 기록 중에 시스템이 멈춘 경우, 불완전한 로그를 폐기 (Undo).

## Ⅲ. 저널링의 3가지 운영 모드 비교

| 모드 | 대상 | 동작 특징 | 장단점 |
|:---:|:---:|:---|:---|
| **Writeback** | 메타데이터 | 메타데이터만 로그에 기록. 순서 보장 안 됨. | 최고 성능, 데이터 손상 위험 높음 |
| **Ordered** | 메타데이터 | **데이터를 먼저 쓰고** 메타데이터를 로그에 기록. | 성능/안전성 균형 (**ext4 기본값**) |
| **Data (Full)** | 데이터 + 메타 | 모든 것을 로그에 기록 후 디스크에 한 번 더 씀. | 최고 안전성, **성능 최악 (I/O 2배)** |

## Ⅳ. 저널링 vs FSCK (비교분석)

| 구분 | FSCK (File System Check) | 저널링 (Journaling) |
|:---:|:---|:---|
| **복구 방식** | 디스크 전체 노드 스캔 및 대조 | 전용 로그 영역(Journal) 확인 |
| **복구 시간** | **디스크 크기에 비례 (매우 느림)** | **로그 크기에 비례 (매우 빠름)** |
| **신뢰성** | 사후적 수정 (손실 가능성) | 예방적 기록 (일관성 보장) |
| **적용** | 구형 파일 시스템 (FAT, ext2) | 현대 파일 시스템 (NTFS, ext3/4) |

## Ⅴ. 기술적 심화: 로그 구조 파일 시스템 (LFS)
- **개념**: 별도의 저널을 두는 대신, 파일 시스템 전체를 하나의 거대한 로그처럼 운영하는 방식.
- **장점**: 모든 쓰기가 순차적으로 발생하여 쓰기 성능 극대화 (SSD의 쓰기 특성에 유리).
- **사례**: F2FS, Log-structured File System.

## Ⅵ. 기술사 관점의 결론 및 제언
- 저널링은 **'로그 기록 비용'**을 지불하여 **'가용성'**을 구매하는 전략임.
- **실무 제언**: 고성능 처리가 중요한 DB 서버 등에서는 저널링의 부하가 성능 병목이 될 수 있음. 이 경우 저널 영역을 별도의 고속 NVMe 드라이브로 분리(External Journal)하거나, 스토리지 레벨의 하드웨어 RAID 컨트롤러(Battery Backup Cache)를 활용하여 소프트웨어 저널링 부하를 상쇄하는 전략이 필요함.
