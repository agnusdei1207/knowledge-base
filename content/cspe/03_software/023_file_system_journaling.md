## 미리 알고가기

- 저널링은 실제 반영 전에 변경 내역을 로그에 먼저 기록하는 방식임
- 메타데이터 저널링은 파일 시스템 구조 정보 중심으로 보호함
- ordered와 writeback과 data journaling은 보호 범위와 성능이 다름

## Ⅰ. 개요

- **정의/개념**: 파일 시스템 저널링은 디렉터리와 inode와 할당 정보 같은 변경 내역을 저널 로그에 먼저 기록해 장애 발생 후에도 파일 시스템 일관성을 빠르게 복구하도록 돕는 무결성 보장 기법임
- **배경/필요성**: 전원 장애나 커널 패닉이 발생하면 메타데이터 갱신이 중간에 끊겨 파일 시스템이 손상될 수 있으므로, 전체 검사 비용을 줄이고 복구 시간을 단축하는 구조가 필요함

## Ⅱ. 특징

- commit된 저널 트랜잭션만 재실행해 전체 파일시스템 검사 범위를 줄임
- 보호 범위에 따라 메타데이터 중심과 데이터 포함 방식으로 나뉨
- 성능과 무결성 수준 사이에 분명한 trade-off가 존재함
- 저널 크기와 flush 정책과 저장장치 특성이 실제 효과를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | Metadata Journaling | Ordered Mode | Data Journaling |
|:---|:---|:---|:---|
| 보호 범위 | 메타데이터 중심 | 데이터 후 메타데이터 순서 보장 | 데이터와 메타데이터 모두 기록 |
| 기록 순서 | 메타데이터만 저널 기록 | 데이터 기록 후 메타데이터 commit | 데이터와 메타데이터를 저널에 기록 |
| 복구 범위 | 메타데이터 구조 복구 | commit 전 미기록 데이터 노출 방지 | 저널에 기록된 데이터·메타데이터 복구 |
| 적용 의미 | 일반 서버 기본 | 범용 균형 | 강한 무결성 요구 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Journal Area | 변경 내역을 순차 기록해 복구 시 재생 또는 롤백의 기준이 되는 로그 영역임 |
| Transaction Group | 함께 완료되어야 하는 메타데이터 변경을 묶어 원자성을 보장함 |
| Commit Record | 어떤 변경 집합이 안전하게 완료됐는지 표시해 복구 판단을 단순화함 |
| Checkpoint Process | 저널 내용을 본래 위치에 반영하고 공간을 회수해 지속 운용을 가능하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 변경 수집      | --> | 저널 기록      | --> | commit 표시    | --> | checkpoint 반영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **변경 수집**: 파일 시스템 메타데이터 변경을 트랜잭션 단위로 모음
2. **저널 기록**: 실제 영역보다 먼저 저널에 변경 내역을 기록함
3. **commit 표시**: 트랜잭션이 안전하게 기록됐음을 표시함
4. **checkpoint 반영**: 나중에 원래 데이터 구조에 반영하고 저널 공간을 회수함

## Ⅵ. 실무 적용 및 유의점

1. 일반 서버 파일 시스템에서는 ordered나 metadata journaling을 쓰되 저널 쓰기 증폭이 지연을 키우지 않도록 저널 크기와 flush 주기를 조정하고 fs latency와 journal write amplification으로 확인함
2. 강한 무결성이 필요한 저장소에서는 data journaling까지 고려하되 데이터 최신성 보장만큼 쓰기 비용도 커지므로 보호 범위를 업무별로 구분하고 recovery data consistency와 write latency와 journal replay success rate로 확인함

## Ⅶ. 결론

파일 시스템 저널링은 성능 기능이 아니라 장애 후 일관성을 빠르게 회복하기 위한 구조이므로 보호 범위와 쓰기 오버헤드의 균형이 핵심 선택 기준임.
