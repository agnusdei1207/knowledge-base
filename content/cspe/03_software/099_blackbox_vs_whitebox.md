## Ⅰ. 개요
- 정의: Blackbox vs Whitebox의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ Input ] -> [ Blackbox (Interface) ] -> [ Output ]
  [ Logic ] -> [ Whitebox (Structure) ] -> [ Path   ]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 블랙박스 | 명세 기반 기능/성능 위주 테스트 | 외부 관찰 |
| 화이트박스 | 소스 코드 내부 로직/구조 테스트 | 내부 분해 |
| 커버리지 | 테스트 수행 범위 측정 지표 | 스캔율 |

> 요약: 외부 기능성과 내부 구조성을 모두 검증하는 양대 축임.

## Ⅲ. 절차
- ASCII 흐름도
  Analysis -> Spec(Black)/Code(White) -> Test Case -> Execution

1. 테스트 대상 분석: 명세서 및 코드 구조 파악함.
2. 기법 선정: 동등분할(Black) 또는 경로테스트(White) 선정함.
3. 케이스 설계: 입력값 및 기대결과, 수행경로 정의함.
4. 결과 분석: 실제 결과와 기대치 비교 및 수정함.

> 요약: 기법별 특성에 맞춘 상호 보완적 케이스 설계임.

## Ⅳ. 문제점
- 블랙박스는 내부 논리 결함 탐지에 한계가 존재함.
- 화이트박스는 소스 코드 의존도가 높아 관리 비용이 큼.

## Ⅴ. 개선방안
- 그레이박스(Graybox) 테스트 도입으로 구조 정보를 활용한 기능 테스트함.
- 자동 커버리지 측정 도구를 활용한 화이트박스 테스트 효율화함.

## Ⅵ. 전망
- AI Test Case Generation을 통해 블랙박스 시나리오 다양화 가속화됨.
- CSF: 리스크 기반 테스트(RBT) 전략을 통한 테스트 강도 차별화임.
