## Ⅰ. 개요
- 원천 시스템에서 데이터를 추출(Extract), 변환(Transform), 적재(Load)하는 일련의 과정임.
- 데이터 파이프라인은 데이터의 흐름을 자동화하고 안정적으로 관리하는 체계임.
- 출제 의도: 데이터 통합 과정의 효율화 기법과 ELT와의 차이점 이해 확인.

## Ⅱ. 구성요소
- 파이프라인 아키텍처
[Source] -> [Extract] -> [Transform] -> [Load] -> [Target]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Extract | 다양한 소스에서 데이터를 수집 (Change Data Capture 등) | 광석 채굴 |
| Transform | 데이터 정제, 결합, 형식 변환 및 비식별화 | 제련 및 가공 |
| Load | 타겟 저장소(DW, Lake)에 최종 데이터 저장 | 창고 입고 |
> 요약: 데이터를 쓸모 있는 정보로 가공하여 목적지까지 전달하는 공정임.

## Ⅲ. 절차
- 데이터 파이프라인 구축 단계
[Requirement] -> [Design] -> [Implementation] -> [Monitoring]

1. 요구사항 분석: 데이터 소스, 주기, 타겟 시스템 및 정제 규칙 확정함.
2. 파이프라인 설계: 배치(Batch) 또는 스트리밍(Streaming) 방식 결정함.
3. 로직 구현: 스케줄링 도구(Airflow 등)를 사용하여 워크플로우 구성함.
4. 장애 관리: 데이터 유실 방지를 위한 재시도(Retry) 및 로깅 체계 구축함.
> 요약: 설계부터 운영까지 자동화된 흐름을 구축하여 데이터 신선도 유지함.

## Ⅳ. 문제점
- 원천 시스템 부하 증가 및 파이프라인 복잡도 상승에 따른 유지보수 어려움.

## Ⅴ. 개선방안
- CDC(Change Data Capture) 활용 및 코드 기반 파이프라인(IaC) 관리 도입.

## Ⅵ. 전망
- 실시간 실시간 분석을 위한 Zero-ETL 아키텍처(클라우드 간 직접 연결) 확산.
- AI 기반 데이터 품질 검사 및 파이프라인 오류 자동 복구 기술 고도화.
