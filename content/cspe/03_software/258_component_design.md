## Ⅰ. 개요
- 정의: 독립적인 기능을 수행하는 단위 부품(Component)을 설계하고 명세화하는 것임
- 배경: 소프트웨어 재사용성 극대화 및 부품 기반 개발(CBD)을 통한 생산성 향상
- 출제 의도
| 대상 | 주요 포인트 | 비중 |
|------|------------|------|
| 설계 원칙 | 인터페이스와 구현의 분리 | 높음 |
| 명세화 | 블랙박스, 화이트박스 관점 | 보통 |

## Ⅱ. 구성요소
- ASCII 구조도
  [ Component ] ---+--- [ Interface (I/O) ] : 외부 노출
                   +--- [ Implementation ] : 내부 로직
                   +--- [ Metadata ] : 설정 정보

- 구성요소 표
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| 인터페이스 | 컴포넌트 간 통신을 위한 약속 (규격) | USB 포트 |
| 캡슐화 | 내부 구현 상세를 숨기고 외부와 격리함 | 시계 케이스 |
| 포트/어댑터 | 외부 환경과의 연결을 유연하게 하는 플러그 | 전원 어댑터 |

> 요약: 내부 구현은 감추고 인터페이스만 드러내어 교체 가능한 부품을 만듦

## Ⅲ. 절차
- ASCII 흐름도
  [컴포넌트 식별] -> [인터페이스 설계] -> [내부 로직 설계] -> [명세서 작성]
     (기능 분해)        (Signatures)       (Algorithm)       (Document)

- 4단계 설명
1. 식별: 도메인 분석을 통해 재사용 가능한 독립적인 기능 단위를 도출함
2. 명세: 입력 파라미터, 출력 결과, 예외 처리 등 외부 규격을 정의함
3. 설계: 인터페이스를 준수하면서 최적의 성능을 내는 내부 구조를 설계함
4. 패키징: 컴포넌트 실행 파일과 함께 설정, 배포 정보 등을 하나로 묶음

> 요약: 규격화된 인터페이스를 중심으로 부품의 독립성과 조립성을 확보함

## Ⅳ. 문제점
- 컴포넌트 간 의존성이 복잡해질 경우 '의존성 지옥(Dependency Hell)' 발생함
- 범용성을 위해 너무 복잡하게 설계하면 오히려 이해하기 어렵고 성능이 떨어짐

## Ⅴ. 개선방안
- (단기) 의존성 주입(DI) 패턴을 사용하여 컴포넌트 간 결합도를 최소화함
- (중기) 컴포넌트 저장소(Repository)를 운영하여 전사적 재사용 체계 구축함
- (장기) 마이크로서비스(MSA)와 연계하여 서비스 단위의 독립적 배포 부품화함

## Ⅵ. 전망
- 로우코드 플랫폼의 확산으로 드래그 앤 드롭 형태의 컴포넌트 조립 개발이 주류가 됨
- AI가 기존 코드를 분석하여 자동으로 재사용 가능한 컴포넌트를 추출해 줄 것임
