## Ⅰ. 개요
- 정의: 독립적 기능을 수행하며 교체 가능한 SW 단위의 내부 구조 및 인터페이스 설계
- 배경: SW 재사용성 극대화 및 CBD(Component Based Development) 구현
- 출제 의도: 컴포넌트의 내부 로직과 외부 인터페이스 명세화 역량 평가

## Ⅱ. 구성요소
- 구조도
  [Component]
  +-- [Provided Interface] (Export)
  +-- [Required Interface] (Import)
  +-- [Inner Logic/State]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 인터페이스 | 서비스 제공/요구를 위한 통로 | USB 포트 규격 |
| 로직/데이터 | 컴포넌트 내부 수행 작업 및 상태 | 가전제품 내부 회로 |
| 배포 단위 | 실행 환경에 독립적으로 설치되는 단위 | 완제품 패키지 |
> 요약: Black-box 형태의 독립적 단위로, 인터페이스를 통해서만 상호작용함

## Ⅲ. 절차
- 흐름도
  컴포넌트 식별 -> 인터페이스 정의 -> 내부 설계 -> 명세화 완료
- 4단계 설명
1. 컴포넌트 식별: 도메인 분석을 통해 응집도 높은 독립 기능 단위 추출
2. 인터페이스 정의: 외부와 소통할 메서드, 파라미터, 반환값 규격 설정
3. 내부 설계: 클래스 다이어그램 등을 활용한 내부 로직 및 데이터 구조화
4. 명세화 완료: 제약 조건, 성능 요구사항을 포함한 상세 설계서 작성
> 요약: 인터페이스와 구현을 분리하여 시스템 유연성 및 유지보수성 확보

## Ⅳ. 문제점
- 컴포넌트 간 과도한 의존성(Coupling) 발생 시 독립적 교체 및 재사용 불가
- 명세화 미흡으로 인한 컴포넌트 오남용 및 통합 단계의 인터페이스 불일치

## Ⅴ. 개선방안
- 의존성 주입(DI) 등을 통한 런타임 결합도 완화 및 테스트 용이성 증대
- 표준화된 인터페이스 기술서(IDL) 및 명세 도구 활용으로 의사소통 강화

## Ⅵ. 전망
- 마이크로서비스(MSA)의 빌딩 블록으로서 컨테이너 기반 배포 체계와 결합
- CSF: 컴포넌트 자산화 전략 수립 및 버전 관리 체계 고도화 필요
