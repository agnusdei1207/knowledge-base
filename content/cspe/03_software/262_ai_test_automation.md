## Ⅰ. 개요
- **정의**: AI가 테스트 케이스 생성·실행·결과 분석을 자율적으로 수행하는 품질 보증 기법
- **배경/필요성**: 소프트웨어 복잡도 증가로 수동 테스트의 커버리지 한계가 심화되어 지능형 자동화가 요구됨
- **비유**: 숙련된 QA 엔지니어를 복제하여 24시간 병렬로 테스트를 수행하게 하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 기반 테스트의 차별점 이해 | 자가 치유(Self-Healing) 테스트 개념 | 기존 자동화와의 차이를 명확히 구분 |

> 요약: AI 테스트 자동화는 테스트 생명주기 전반에 AI를 적용하여 품질과 속도를 동시에 확보하는 기법임

## Ⅱ. 구성요소
```text
[Code/UI Change] --분석--> [AI Test Engine]
                               |
              +----------------+----------------+
              |                |                |
              v                v                v
       [TC Generator]  [Test Executor]  [Result Analyzer]
              |                |                |
              v                v                v
       [Coverage Map]  [Self-Healing]   [Defect Report]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| TC Generator | 코드 변경 영향도를 분석하여 테스트 케이스를 자동 생성함 | 출제자가 시험 범위에 맞춰 문제를 만드는 것 |
| Self-Healing | UI/API 변경 시 테스트 스크립트를 자동 수정함 | 도로 공사 시 내비게이션이 경로를 재탐색하는 것 |
| Result Analyzer | 테스트 결과를 분류하고 근본 원인을 추론함 | 의사가 검사 결과를 종합 판독하는 것 |

> 요약: TC 생성-실행-분석의 3개 엔진이 자가 치유 능력을 갖추고 테스트를 자율 수행함

## Ⅲ. 절차
```text
변경 감지 --> TC 생성 --> 테스트 실행 --> 결과 분석/학습
    |            |            |               |
    v            v            v               v
  Diff분석   우선순위화    병렬수행      회귀패턴학습
```
- 1단계: 코드 커밋·UI 변경을 감지하여 영향 범위를 식별함
- 2단계: 변경 영향도 기반으로 테스트 케이스를 생성하고 우선순위를 부여함
- 3단계: 생성된 TC를 병렬 환경에서 실행하고 실패 시 자가 치유를 시도함
- 4단계: 결과를 분석하여 결함 보고서를 생성하고 회귀 패턴을 학습함

> 요약: 변경 감지부터 결과 학습까지 4단계가 자율 순환하는 구조임

## Ⅳ. 문제점
- 학습 데이터 부족: 신규 프로젝트는 과거 테스트 이력이 없음 — AI 모델 정확도가 낮아짐
- 허위 양성 과다: 정상 변경을 결함으로 오탐함 — 개발자의 신뢰도가 하락하고 무시 패턴이 형성됨
- 블랙박스 판단: AI의 TC 선택 근거가 불투명함 — 감사·규제 대응이 곤란함

> 요약: 데이터 부족·오탐·불투명성이 AI 테스트 자동화의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 기존 수동 테스트 이력을 정제하여 초기 학습 데이터셋으로 활용
2. 중기: 오탐 피드백 루프를 구축하여 모델 재학습 주기를 단축
3. 장기: XAI 기반 TC 선택 근거 설명 기능을 탑재하여 감사 추적성 확보

> 요약: 데이터 확보-피드백 루프-설명 가능성 순으로 단계적 성숙이 필요함

## Ⅵ. 전망
- 발전 방향: 요구사항 문서로부터 E2E 테스트를 자동 생성하는 Autonomous QA로 진화함
- 기술사적 판단: AI 테스트는 CI/CD 파이프라인의 표준 구성 요소로 정착될 것임
- 기술사 제언: 테스트 자동화 ROI 측정 체계와 함께 점진적 도입 전략을 수립할 필요
