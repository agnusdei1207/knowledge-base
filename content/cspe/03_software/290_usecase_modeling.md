## Ⅰ. 개요
- 정의: 사용자 관점에서 시스템이 제공해야 하는 기능과 외부 상호작용을 기술하는 기법임
- 배경: 시스템 경계와 사용자 목표를 기준으로 기능 범위와 예외 흐름을 합의할 필요
- 출제 의도: 시스템 경계 설정 및 사용자 중심 기능 정의 능력 검증

## Ⅱ. 구성요소
- ASCII 구조도
     [Actor] --- (Usecase) --- [System Boundary]
                   ^   ^
               <<inc>> <<ext>>
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 액터(Actor) | 시스템과 상호작용하는 외부 개체(사람/시스템) | 손님 |
| 유스케이스 | 시스템이 수행하는 단위 기능의 집합 | 메뉴판 |
| 관계 | 포함(Include), 확장(Extend), 일반화 관계 | 주문 옵션 |
> 요약: 외부 액터와 시스템 내부 기능 간의 관계를 시각화하여 표현함

## Ⅲ. 절차
- ASCII 흐름도
  Actor ID -> Usecase ID -> Relationship -> Specification
- 4단계 설명
1. Actor ID: 시스템 외부에서 자극을 주는 모든 개체 식별함
2. Usecase ID: 액터가 시스템을 통해 달성하려는 목표 기반 기능 식별함
3. Relationship: 유스케이스 간의 포함, 확장, 일반화 관계 설정함
4. Specification: 각 유스케이스에 대한 상세 흐름 및 예외 상황 기술함
> 요약: 액터와 기능을 식별한 후 이들의 논리적 관계와 상세 흐름을 명세화함

## Ⅳ. 문제점
- 작성자마다 유스케이스 목표 수준과 상세 흐름 범위가 달라 기능 중복·누락이 발생할 수 있음

## Ⅴ. 개선방안
- 팀 표준 템플릿과 유스케이스 수준(Summary, User-goal)을 정의하고 요구사항 ID와 연결함

## Ⅵ. 전망
- 발전 방향: 자연어 처리 기반 요구사항-유스케이스 자동 변환 및 정적 분석 도구 연동 강화
- CSF: 비즈니스 목표와의 정렬(Alignment) 확인 및 예외 흐름(Alternative Path)의 철저한 발굴이 필수임
