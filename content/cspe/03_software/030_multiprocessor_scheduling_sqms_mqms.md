## 미리 알고가기

- SQMS는 단일 전역 큐를 여러 프로세서가 공유하는 방식임
- MQMS는 프로세서별 개별 큐를 두는 방식임
- 다중 프로세서 스케줄링의 핵심은 부하 분산과 캐시 지역성 균형임

## Ⅰ. 개요

- **정의/개념**: 다중 프로세서 스케줄링은 여러 CPU 코어에 실행 가능한 작업을 배분하는 운영체제 정책이며, 대표 구조로 단일 큐 기반 SQMS와 코어별 큐 기반 MQMS가 있음
- **배경/필요성**: 멀티코어 환경에서는 단일 CPU 스케줄링처럼 단순히 순서를 정하는 것만으로는 부족하고, 코어 간 부하 균형과 캐시 지역성과 락 경쟁을 함께 고려해야 함

## Ⅱ. 특징

- SQMS는 전역 공정성이 좋고 idle 코어 활용이 쉽지만 큐 락 경합이 생길 수 있음
- MQMS는 캐시 지역성과 확장성이 좋지만 부하 불균형이 생기기 쉬움
- 실제 운영체제는 work stealing이나 load balancing으로 두 방식 장단점을 절충함
- 워크로드 성격에 따라 최적 구조가 달라져 고정된 정답이 없음

## Ⅲ. 종류 및 비교

| 판단 기준 | SQMS | MQMS |
|:---|:---|:---|
| 큐 구조 | 전역 단일 큐 | 코어별 개별 큐 |
| 장점 | 공정성과 유휴 코어 활용 용이 | 확장성과 캐시 지역성 우수 |
| 한계 | 락 경합과 cache bouncing | 부하 불균형 가능 |
| 적합 환경 | 작업 편차 큰 일반 워크로드 | 코어 지역성 중요한 병렬 처리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Run Queue | 작업 대기열로 SQMS는 하나, MQMS는 여러 개가 존재해 성능 구조를 갈라놓음 |
| Load Balancer | 코어 간 작업 편차를 조정해 유휴 코어와 과부하 코어를 재분배함 |
| Processor Affinity | 작업이 같은 코어에 머물도록 유도해 캐시 재사용과 지역성을 높임 |
| Work Stealing Path | MQMS에서 빈 코어가 다른 큐의 작업을 가져오며 균형을 회복함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 큐 적재    | --> | 코어 배정      | --> | 실행/대기 반복 | --> | 부하 재조정    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 큐 적재**: 새 작업을 전역 큐나 개별 코어 큐에 넣음
2. **코어 배정**: 스케줄러가 작업을 특정 프로세서에 할당함
3. **실행 및 대기 반복**: 작업이 실행되거나 다시 큐로 돌아감
4. **부하 재조정**: 편차가 크면 migration이나 stealing을 수행함

## Ⅵ. 실무 적용 및 유의점

1. 작업 편차가 큰 범용 서버는 SQMS나 hybrid 큐가 유리하지만 전역 큐 락이 병목이 되지 않도록 per-CPU 보조 구조를 두고 scheduler lock contention과 throughput scaling으로 확인함
2. 캐시 지역성이 중요한 병렬 런타임은 MQMS가 맞지만 부하가 한쪽으로 몰리면 유휴 코어가 생기므로 work stealing과 affinity 정책을 함께 두고 load imbalance ratio와 idle core time과 migration count로 확인함

## Ⅶ. 결론

다중 프로세서 스케줄링의 핵심은 공정성 자체보다 부하 분산과 캐시 지역성 사이 균형을 어떤 큐 구조로 구현하느냐에 있음.
