## 미리 알고가기

- SQMS는 단일 전역 큐를 여러 프로세서가 공유하는 방식임
- MQMS는 프로세서별 개별 큐를 두는 방식임
- 큐 구조는 코어별 작업 편차와 캐시 재사용률을 함께 변화시킴

## 작성 근거(검토용)

- SQMS·MQMS를 큐·작업 선택·친화도·부하 조정·경합·적용 업무로 비교함
- 작업 삽입·코어 선택·실행·재큐잉·이동을 큐 상태가 바뀌는 실제 흐름으로 유지함
- 범용 서버와 병렬 런타임을 분리해 큐 경합과 코어 유휴시간을 검증함

## Ⅰ. 개요

- **정의/개념**: 다중 프로세서 스케줄링은 여러 CPU 코어에 실행 가능한 작업을 배분하는 운영체제 정책이며, 대표 구조로 단일 큐 기반 SQMS와 코어별 큐 기반 MQMS가 있음
- **배경/필요성**: 멀티코어에서 작업 분배가 코어별 부하·캐시 재사용·큐 경합에 영향을 주므로 실행 큐와 작업 이동 기준이 필요함

## Ⅱ. 특징

- SQMS는 모든 코어가 전역 큐에서 작업을 가져가므로 유휴 코어가 남은 작업을 선택하지만 큐 락 경합이 발생할 수 있음
- MQMS는 코어별 큐에서 작업을 반복 실행해 캐시 재사용을 유지하지만 큐별 작업량 차이가 생길 수 있음
- 운영체제는 work stealing과 load balancing으로 큐별 작업량 차이를 조정함
- 작업 이동 빈도와 캐시 재사용 요구에 따라 전역·코어별 큐 구조를 선택함

## Ⅲ. 종류 및 비교

| 판단 기준 | SQMS | MQMS |
|:---|:---|:---|
| 큐 구조 | 전역 단일 큐 | 코어별 개별 큐 |
| 작업 선택 | 모든 코어가 전역 큐에서 선택 | 코어가 로컬 큐에서 선택 |
| CPU 친화도 | 작업 이동 가능성 큼 | 같은 코어 반복 실행 |
| 부하 조정 | 전역 큐에서 자연 분산 | 이동·work stealing 필요 |
| 주요 제약 | 큐 락 경합·캐시 바운싱 | 큐별 작업 편차·이동 비용 |
| 대표 환경 | 작업 공유가 잦은 서버 | 캐시 재사용이 필요한 병렬 처리 |

> 요약: SQMS는 전역 큐로 부하를 공유하고, MQMS는 코어별 큐로 캐시 지역성을 유지하며 이동·work stealing으로 편차를 조정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 실행 큐 | SQMS는 전역 하나, MQMS는 코어별 큐를 사용함 |
| 부하 분산기 | 코어별 실행 가능 작업 수를 비교해 이동 대상을 정함 |
| CPU 친화도 | 작업의 이전 실행 코어와 캐시 재사용 정보를 유지함 |
| Work stealing 경로 | 유휴 코어가 다른 로컬 큐에서 작업을 가져옴 |

> 요약: 실행 큐 구조와 CPU 친화도·부하 분산·work stealing이 작업 이동과 캐시 재사용을 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 큐 적재    | --> | 코어 배정      | --> | 실행/대기 반복 | --> | 부하 재조정    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 큐 적재**: 새 작업을 전역 큐 또는 CPU 친화도를 반영한 로컬 큐에 넣음
2. **코어 선택**: 코어가 전역·로컬 큐에서 다음 작업을 선택함
3. **실행·재큐잉**: 선점·대기 해제된 작업을 정책에 맞는 큐에 다시 넣음
4. **부하 재조정**: 큐 길이 편차가 기준을 넘으면 작업 이동·work stealing을 수행함

## Ⅵ. 실무 사례

1. 범용 서버는 전역 큐 경합을 분산하고 스케줄러 락 대기시간과 코어별 처리량을 확인함
2. 병렬 런타임은 MQMS와 work stealing을 적용하고 코어 유휴시간과 작업 이동 수를 확인함

## Ⅶ. 결론

- 다중 프로세서 스케줄링은 작업 편차·CPU 친화도·큐 경합을 기준으로 SQMS·MQMS를 선택함
