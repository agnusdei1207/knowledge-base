## Ⅰ. 개요
- **정의**: 소프트웨어 카탈로그·템플릿·문서·플러그인을 단일 UI로 통합한 오픈소스 개발자 포털 프레임워크
- **배경/필요성**: 마이크로서비스 증가로 서비스·소유권·문서가 분산되어 개발자의 탐색 비용이 급증함
- **비유**: 대형 도서관의 통합 검색 시스템처럼 모든 서비스·도구·문서를 한곳에서 탐색하는 창구

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IDP 구현체로서의 Backstage 이해 | Software Catalog·Template·Plugin 아키텍처 | 단순 대시보드와 개발자 포털 구분 |

> 요약: 분산된 서비스·도구·문서를 단일 포털로 통합하여 개발자 경험을 개선하는 프레임워크임

## Ⅱ. 구성요소
```text
[Developer] --> [Backstage UI]
                     |
       +-------------+-------------+
       v             v             v
  [Software     [Software     [TechDocs]
   Catalog]      Templates]
       |
       v
  [Plugin Ecosystem]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Software Catalog | 서비스·라이브러리·인프라의 소유권·메타데이터 중앙 등록부 | 도서 목록 카드 |
| Software Templates | 골든 패스 기반 프로젝트 스캐폴딩 자동화 | 대출 신청서 양식 |
| TechDocs | 코드 저장소와 연동된 docs-as-code 기술 문서 시스템 | 도서관 참고자료실 |
| Plugin Ecosystem | CI/CD, 모니터링 등 외부 도구 통합 확장 모듈 | 도서관 부대시설 |

> 요약: 소프트웨어 카탈로그, 템플릿, 테크독스, 플러그인이 Backstage의 핵심 구성임

## Ⅲ. 절차
```text
Register Service --> Catalog Sync --> Template Scaffold --> Plugin Integrate
```
- 1단계: 서비스 메타데이터(`catalog-info.yaml`)를 코드 저장소에 등록
- 2단계: Backstage가 저장소를 주기적으로 스캔하여 카탈로그 자동 동기화
- 3단계: 신규 서비스 생성 시 표준 템플릿으로 프로젝트 스캐폴딩
- 4단계: CI/CD·모니터링·보안 플러그인을 포털에 통합하여 단일 뷰 제공

> 요약: 서비스 등록, 카탈로그 동기화, 템플릿 스캐폴딩, 플러그인 통합 순으로 운영함

## Ⅳ. 문제점
- 카탈로그 정합성: 메타데이터 미등록·미갱신 서비스가 존재하면 카탈로그 신뢰도 저하
- 플러그인 파편화: 자체 플러그인 난립 시 유지보수 부담과 버전 충돌 발생
- 초기 도입 비용: 커스터마이징과 플러그인 개발에 상당한 초기 투자가 필요함

> 요약: 카탈로그 정합성, 플러그인 파편화, 초기 도입 비용이 주요 과제임

## Ⅴ. 개선방안
1. 단기: CI 파이프라인에 카탈로그 메타데이터 검증 게이트 추가
2. 중기: 플러그인 거버넌스 정책 수립 및 공식 마켓플레이스 기반 관리
3. 장기: 도입 로드맵을 단계별로 수립하여 초기 범위를 핵심 기능으로 한정

> 요약: 메타데이터 검증 자동화, 플러그인 거버넌스, 단계별 도입으로 포털 품질을 확보함

## Ⅵ. 전망
- 발전 방향: CNCF 졸업 프로젝트로서 IDP 사실상 표준 프레임워크로 자리매김
- 기술사적 판단: 플랫폼 엔지니어링(295 참조)의 프론트엔드 구현체 역할 수행
- 기술사 제언: 소프트웨어 카탈로그를 조직의 서비스 거버넌스 허브로 활용 필요
