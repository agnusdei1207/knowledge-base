# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 계보를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터가 어디서 생성되어 어떤 변환을 거쳐 어디에 사용되는지 추적하는 기록
- **왜 필요한가**: 지표 값이 바뀌었을 때 원천, 변환 SQL, 배치, 대시보드 영향 범위를 모르면 장애 분석과 감사 대응에 시간이 걸린다. 계보는 원인 추적과 변경 영향 분석의 근거가 된다.
- **핵심 직관**: 택배 송장처럼 출발지, 중간 허브, 도착지, 처리 시각을 남겨 데이터 이동 경로를 확인한다.

## 깊이 이해
- **배경·문제의식**: 데이터 파이프라인이 많아지면 하나의 컬럼 변경이 수십 개 마트와 리포트를 깨뜨릴 수 있다. 데이터 계보는 테이블, 컬럼, 작업, 대시보드 사이의 의존 관계를 그래프로 관리하여 변경 전 영향 범위를 알려준다.
- **작동 원리**: ETL/ELT 도구, SQL 파서, 스케줄러, BI 도구에서 메타데이터를 수집한다. 이 정보를 데이터셋 단위와 컬럼 단위 계보로 연결하고, 실패/변경 시 downstream 영향 대상을 표시한다.
- **비유**: 전기 배선도와 같다. 스위치 하나를 바꾸기 전에 연결된 조명과 차단기를 확인해야 한다.
- **구체 예시**: `customer_id` 컬럼 타입을 INT에서 STRING으로 변경하기 전 downstream 테이블 18개, Airflow DAG 4개, 대시보드 7개를 파악하면 사전 공지와 테스트 범위를 정할 수 있다.
- **흔한 오해·주의점**: 테이블 단위 계보만으로는 충분하지 않다. 개인정보 마스킹, 지표 변경, 컬럼 삭제 영향은 컬럼 단위 계보가 있어야 판단 가능하다.

## 연결 개념
- 데이터 카탈로그 - 계보를 검색 화면에 노출
- ETL/ELT 파이프라인 - 계보 수집의 주요 출처
- 데이터 거버넌스 - 감사, 변경 승인, 책임 추적에 활용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 계보 답안은 추적 개념 설명을 넘어 영향 분석, 장애 원인 추적, 규제 감사 대응 지표까지 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 계보는 원천, 변환, 적재, 소비 자산 간 의존 관계를 테이블/컬럼 단위로 추적하는 메타데이터 그래프임.
> 2. **가치**: 변경 영향 분석 시간과 장애 원인 추적 시간을 줄이고, 개인정보 처리 경로와 감사 증적을 제공함.
> 3. **판단 포인트**: 테이블 단위, 컬럼 단위, 런타임 계보 중 업무 위험도에 맞는 깊이를 선택해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 변경 영향 분석 역량 확인 | upstream/downstream, 컬럼 단위 계보 | 단순 로그 추적으로 축소 |
| 거버넌스/감사 대응 확인 | PII 흐름, 변환 이력, 승인 증적 | 개인정보 처리 경로 누락 |
| 구현 방식 판단 확인 | SQL 파싱, 오케스트레이터, BI 메타데이터 수집 | 도구명만 나열 |

> 요약: 데이터 계보는 장애 분석과 감사 대응을 위해 의존 관계를 그래프와 지표로 관리하는 체계임.

---

## Ⅰ. 개요 및 필요성

데이터 계보는 데이터 흐름 추적 체계임. 데이터 기반 의사결정에서 지표 오류와 컬럼 변경은 다수 리포트에 영향을 준다. 계보는 원천부터 소비까지의 의존 관계를 기록해 변경 영향, 장애 원인, 감사 증적을 제공한다.

---

## Ⅱ. 구조 및 구성요소

```text
Source Table -> Transform Job -> Target Table -> Data Mart -> BI/API
          +-> Column Mapping
          +-> Run Log/Owner
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 원천 자산 | DB, 파일, 이벤트의 시작점 | schema, owner 필요 |
| 변환 작업 | SQL, Spark, dbt, Airflow task | 코드와 실행 로그 연결 |
| 대상 자산 | 마트, 피처, 리포트 산출 | downstream 영향 분석 |
| 계보 저장소 | 노드/엣지 그래프 관리 | table, column, runtime 수준 |

> 요약: 계보는 원천, 변환, 대상, 사용처를 노드와 엣지로 연결한 메타데이터 그래프임.

---

## Ⅲ. 동작원리 및 흐름도

```text
메타데이터 수집 -> SQL/작업 파싱 -> 노드/엣지 생성 -> 영향 범위 조회 -> 변경/감사 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | DB, ETL, BI 메타데이터 수집 | 주요 시스템 coverage 90% 이상 |
| 2 | SQL, DAG, Spark job 의존성 파싱 | 파싱 실패율 3% 이하 |
| 3 | 테이블/컬럼 노드와 엣지 생성 | 컬럼 매핑률 85% 이상 |
| 4 | 변경 전 downstream 영향 분석 | 영향 대상 조회 5분 이하 |
| 5 | 변경 승인과 감사 증적 보관 | 변경 이력 1년 이상 |

> 요약: 계보는 수집, 파싱, 그래프 생성, 영향 조회, 감사 기록의 절차로 운영됨.

---

## Ⅳ. 특징

| 구분 | 테이블 단위 계보 | 컬럼 단위 계보 | 판단 포인트 |
|:---|:---|:---|:---|
| 범위 | 데이터셋 간 이동 | 컬럼 변환과 매핑 | PII, 핵심 지표 |
| 구현 | 수집 난이도 낮음 | SQL 파싱 필요 | 파싱 실패율 |
| 활용 | 시스템 영향 분석 | 지표 오류 원인 추적 | 컬럼 매핑률 85% 이상 |
| 한계 | 세부 영향 불명 | 동적 SQL 처리 난도 | 수동 보정 절차 |

> 요약: 감사와 지표 품질이 필요한 영역은 컬럼 단위 계보까지 확보해야 함.

| 비용/처리 | 수동 조사 | SQL 파싱 자동화 | 월 변경 100건 이상 |

> 요약: 계보는 변경 빈도와 감사 요구가 큰 데이터 플랫폼에서 필수 통제 수단임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 누락 계보 | 비표준 SQL, 수동 작업 | 표준 SQL 규칙, 수동 등록 워크플로 | coverage 90% 이상 |
| 잘못된 영향 분석 | 컬럼 매핑 오류 | 샘플 검증, owner 승인 | false mapping 1% 이하 |

> 요약: 계보 정확도는 자동 파싱과 owner 검증을 결합해 관리해야 함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 수집 범위 | 핵심 파이프라인 90% 이상 | lineage coverage report |
| 분석 시간 | 영향 범위 조회 5분 이하 | 변경 요청 처리 로그 |
| 감사 증적 | 변경 이력 1년 이상 | 승인 기록, 실행 로그 |

> 요약: 계보 운영은 수집 범위, 분석 시간, 감사 증적 보존으로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 수집 연계: dbt, Airflow, Spark, BI 메타데이터를 OpenLineage/Marquez로 수집해 테이블 계보 coverage 90% 이상 확보
2. 컬럼 계보: 핵심 지표와 PII 컬럼은 SQL 파서 기반 컬럼 매핑률 85% 이상을 목표로 owner 승인 절차 적용
3. 변경 통제: 컬럼 삭제, 타입 변경, 지표 산식 변경은 downstream 조회 결과를 변경 요청서에 첨부

**결론 (2줄):**
- 기술사 판단: 단순 영향 분석은 테이블 계보, 개인정보와 지표 감사는 컬럼 계보까지 적용함
- 향후 방향: 데이터 계약, 카탈로그, 품질 검증과 결합되어 변경 전 자동 차단 체계로 발전함
