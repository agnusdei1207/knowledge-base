## 미리 알고가기

- 데이터 계보는 데이터가 원천에서 산출물까지 이동·변환된 관계와 이력을 추적함
- Dataset은 테이블·파일·토픽처럼 작업이 읽거나 쓰는 데이터 단위임
- Job은 Dataset을 입력받아 다른 Dataset을 생성·변경하는 처리 단위임
- Run은 특정 시점에 실행된 Job의 한 인스턴스이며 시작·완료·실패 상태를 가짐
- 열 수준 계보는 산출 열이 어떤 원천 열과 변환식에서 생성됐는지 추적함
- 영향 분석은 변경 대상의 하위 Dataset·Job·보고서 범위를 찾고 원인 분석은 상위 경로를 추적함

## 작성 근거(검토용)

- 계보는 Dataset·Job·Run 관계와 설계·실행 계보, 열 수준 추적·영향 분석을 핵심으로 선정함
- 비교표는 설계 계보와 실행 계보의 생성 시점·근거·상태·활용·누락·적합 조건을 대비함
- 절차는 Job 실행 이벤트가 입력·출력 관계로 수집되고 그래프에 병합되는 실제 흐름을 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 영향 분석과 원인 추적 방향을 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 계보는 Dataset·Job·Run의 입력·출력과 변환 관계를 기록해 원천·변경 영향·장애 원인을 추적하는 메타데이터 체계임
- **배경/필요성**: 파이프라인과 보고서의 산출값이 어떤 원천·변환에서 생성됐는지 확인하고 변경·오류의 전파 범위를 계산하기 위해 종단 간 관계 정보가 필요함

## Ⅱ. 특징

- Dataset과 Job을 노드로, 읽기·쓰기·변환을 간선으로 표현해 상·하위 경로를 탐색함
- 테이블 수준은 시스템 간 흐름을, 열 수준은 산출 열의 직접 원천과 변환식을 추적함
- 설계 계보는 선언된 입력·출력을, 실행 계보는 Run에서 관찰된 데이터와 상태를 기록함
- 스키마·소유자·품질·실행 상태를 계보와 결합해 변경 영향과 장애 원인을 좁힘
- 동적 SQL·사용자 정의 함수·수동 파일 이동을 수집하지 못하면 계보 그래프가 단절됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 설계 계보 | 실행 계보 |
|:---|:---|:---|
| 생성 시점 | 코드 분석·컴파일·배포 시 생성 | Job Run의 시작·완료·실패 시 생성 |
| 관계 근거 | 선언된 입력·출력·SQL·모델 정의 | 실제 실행이 읽고 쓴 Dataset 관찰 |
| 상태 정보 | 코드 위치·버전·정적 스키마 | Run ID·시각·상태·입출력 범위 |
| 주요 활용 | 배포 전 변경 영향·문서화 | 장애 원인·감사·품질 결과 추적 |
| 누락 조건 | 동적 생성 경로를 정적으로 해석하지 못함 | 실행되지 않은 경로와 미계측 작업이 보이지 않음 |
| 적합 조건 | CI·모델 저장소 중심 관리 | 파이프라인 실행 관찰과 실제 이력 필요 |

> 요약: 설계 계보는 선언된 변환을 배포 전에 보여주고 실행 계보는 Run에서 관찰된 입력·출력과 상태를 기록함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Dataset | 입력·출력 테이블·파일·토픽을 네임스페이스와 이름으로 식별함 |
| Job | Dataset을 읽고 변환해 산출물을 만드는 코드·쿼리·Task를 나타냄 |
| Run | Job의 실행 ID·시각·상태와 실제 입력·출력 범위를 기록함 |
| Facet | 스키마·열 변환·소스 코드·품질·소유자·버전을 관계에 추가함 |
| Collector·Emitter | 처리 엔진·오케스트레이터에서 설계·실행 이벤트를 수집함 |
| Lineage Graph·UI | 자산 관계를 병합하고 상·하위 경로와 열 수준 영향을 탐색함 |

```text
Input Dataset -> Job·Run -> Output Dataset -> Report·API
       |            |             |
     Schema      Status       Quality·Owner
```

> 요약: Dataset·Job·Run과 스키마·품질 메타데이터를 그래프로 연결해 원천과 영향 경로를 추적함.

## Ⅴ. 원리 및 절차 흐름도

```text
Job 시작 이벤트 -> 입력 Dataset 기록 -> 변환 실행 -> 출력 Dataset 기록 -> 그래프 병합
```

1. **실행 식별**: Emitter가 Job 이름과 고유 Run ID로 시작 이벤트를 생성함
2. **입력 연결**: 실제 읽은 Dataset·스키마·입력 범위를 Run에 연결함
3. **변환 관찰**: SQL·연산자·열 매핑에서 산출 관계와 소스 정보를 추출함
4. **출력 연결**: 완료·실패 상태와 확인된 출력 Dataset·품질·통계를 기록함
5. **관계 병합**: Backend가 여러 Run 이벤트를 Dataset·Job 그래프에 누적함

> 요약: 실행 이벤트의 입력·변환·출력을 Dataset·Job·Run 그래프에 병합해 실제 데이터 경로를 구성함.

## Ⅵ. 실무 사례

1. 테이블 열 변경은 하위 열 계보를 탐색하고 영향 Job 수·미연결 산출물 수를 확인함
2. 지표 오류 분석은 실패 Run에서 상위 원천을 추적하고 원인 식별 시간·계보 단절 수를 확인함

## Ⅶ. 결론

- 데이터 계보는 자산 식별자·수집 범위·열 단위 정확성·실행 상태 연결과 단절 경로 수로 관리해야 함
