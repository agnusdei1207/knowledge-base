## 미리 알고가기

- 데이터 계보는 데이터가 원천에서 산출물까지 이동·변환된 관계와 이력을 추적함
- 데이터셋(Dataset)은 테이블·파일·토픽처럼 작업이 읽거나 쓰는 데이터 단위임
- 작업(Job)은 데이터셋을 입력받아 다른 데이터셋을 생성·변경하는 처리 단위임
- 실행 이력(Run)은 특정 시점에 수행된 작업의 한 인스턴스이며 시작·완료·실패 상태를 가짐
- 열 수준 계보는 산출 열이 어떤 원천 열과 변환식에서 생성됐는지 추적함
- 영향 분석은 변경 대상의 하위 데이터셋·작업·보고서 범위를 찾고 원인 분석은 상위 경로를 추적함

## 작성 근거(검토용)

- 계보는 데이터셋·작업·실행 이력 관계와 설계·실행 계보, 열 수준 추적·영향 분석을 핵심으로 선정함
- 비교표는 설계 계보와 실행 계보의 생성 시점·근거, 주요 활용, 누락 조건을 대비함
- 절차는 작업 실행 이벤트가 입력·출력 관계로 수집되고 그래프에 병합되는 실제 흐름을 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 영향 분석과 원인 추적 방향을 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 계보는 데이터셋·작업·실행 이력의 입력·출력과 변환 관계를 기록해 원천과 장애 원인을 추적하고 변경 영향 범위를 계산하는 메타데이터 체계임
- **배경/필요성**: 파이프라인과 보고서의 산출값이 어떤 원천·변환에서 생성됐는지 확인하고 변경·오류의 전파 범위를 계산하기 위해 종단 간 관계 정보가 필요함

### 쉽게 이해하기 (학습용)
- 보고서 숫자가 어느 원천과 변환을 거쳐 만들어졌는지 연결선을 따라 추적하는 지도임

## Ⅱ. 특징

- 데이터셋과 작업을 노드로, 읽기·쓰기·변환을 간선으로 표현해 상·하위 경로를 탐색함
- 테이블 수준은 시스템 간 흐름을, 열 수준은 산출 열의 직접 원천과 변환식을 추적함
- 설계 계보는 선언된 입력·출력을, 실행 계보는 실행 이력에서 관찰된 데이터와 상태를 기록함
- 스키마·소유자·품질·실행 상태를 계보와 결합해 변경 영향과 장애 원인을 좁힘
- 동적 SQL·사용자 정의 함수·수동 파일 이동을 수집하지 못하면 계보 그래프가 단절됨

### 쉽게 이해하기 (학습용)
- 설계 계보는 예정 경로, 실행 계보는 실제 지나간 경로이며 둘 다 누락 조건이 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 설계 계보 | 실행 계보 |
|:---|:---|:---|
| 생성 시점·근거 | 코드 분석·컴파일·배포 시 선언된 입력·출력·SQL·모델 정의로 생성 | 작업 실행의 시작·완료·실패 시 실제 읽고 쓴 데이터셋 관찰로 생성 |
| 주요 활용 | 배포 전 변경 영향·문서화 | 장애 원인·감사·품질 결과 추적 |
| 누락 조건 | 동적 생성 경로를 정적으로 해석하지 못함 | 실행되지 않은 경로와 미계측 작업이 보이지 않음 |

> 요약: 설계 계보는 선언된 정의를 배포 전에 분석하고 실행 계보는 실행 이력에서 관찰된 입출력을 기록하되 각각 동적 경로와 미계측 작업을 놓침.

### 쉽게 이해하기 (학습용)
- 변경 전 영향은 설계 계보, 장애 원인과 감사에는 실행 계보가 더 직접적임

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터셋(Dataset) | 입력·출력 테이블·파일·토픽을 네임스페이스와 이름으로 식별함 |
| 작업(Job) | 데이터셋을 읽고 변환해 산출물을 만드는 코드·쿼리 실행 단위를 나타냄 |
| 실행 이력(Run) | 작업의 실행 ID·시각·상태와 실제 입력·출력 범위를 기록함 |
| 부가 메타데이터 | 스키마·열 변환·소스 코드·품질·소유자·버전을 관계에 추가함 |
| 수집기·이벤트 발행기 | 처리 엔진·오케스트레이터에서 설계·실행 이벤트를 수집함 |
| 계보 그래프·UI | 자산 관계를 병합하고 상·하위 경로와 열 수준 영향을 탐색함 |

```text
입력 데이터셋 -> 작업·실행 이력 -> 출력 데이터셋 -> 보고서·API
       |            |             |
     스키마       상태          품질·소유자
```

> 요약: 데이터셋·작업·실행 이력과 스키마·품질 메타데이터를 그래프로 연결해 원천과 영향 경로를 추적함.

### 쉽게 이해하기 (학습용)
- 자료, 변환 작업, 실행 기록과 스키마·품질 정보를 관계 그래프로 연결함

## Ⅴ. 원리 및 절차 흐름도

```text
작업 시작 이벤트 -> 입력 데이터셋 기록 -> 변환 실행 -> 출력 데이터셋 기록 -> 그래프 병합
```

1. **실행 식별**: 이벤트 발행기가 작업 이름과 고유 실행 ID로 시작 이벤트를 생성함
2. **입력 연결**: 실제 읽은 데이터셋·스키마·입력 범위를 실행 이력에 연결함
3. **변환 관찰**: SQL·연산자·열 매핑에서 산출 관계와 소스 정보를 추출함
4. **출력 연결**: 완료·실패 상태와 확인된 출력 데이터셋·품질·통계를 기록함
5. **관계 병합**: 계보 저장소가 여러 실행 이벤트를 데이터셋·작업 그래프에 누적함

> 요약: 실행 이벤트의 입력·변환·출력을 데이터셋·작업·실행 이력 그래프에 병합해 실제 데이터 경로를 구성함.

### 쉽게 이해하기 (학습용)
- 작업 시작·완료 때 실제 입력과 출력을 받아 기존 관계 그래프에 병합함

## Ⅵ. 실무 사례

1. 테이블 열 변경은 하위 열 계보를 탐색하고 영향 작업 수·미연결 산출물 수를 확인함
2. 지표 오류 분석은 실패 실행 이력에서 상위 원천을 추적하고 원인 식별 시간·계보 단절 수를 확인함

### 쉽게 이해하기 (학습용)
- 보고서 오류와 컬럼 변경 영향 분석에서 끊긴 경로·미수집 작업·열 연결 정확도를 확인함

## Ⅶ. 결론

- 데이터 계보는 자산 식별자·수집 범위·열 단위 정확성·실행 상태 연결률·단절 경로 수를 기준으로 관리해야 함
- 예쁜 그래프보다 미계측 작업·동적 SQL·수동 파일 경로를 발견하고 원인 추적 시간을 줄이는 데 집중해야 함

### 쉽게 이해하기 (학습용)
- 그래프 시각화보다 누락 경로 탐지와 장애 원인까지의 추적 시간 단축을 우선함
