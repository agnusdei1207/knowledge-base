## Ⅰ. 개요
- 실제 개발 현장에서 가장 빈번하게 사용되는 핵심 디자인 패턴들의 세부 특징임.
- 싱글톤(생성), 팩토리 메서드(생성), 옵저버(행위)가 대표적임.
- 출제 의도: 개별 패턴의 구현 원리, 장단점 및 활용 시나리오 분석 역량 확인.

## Ⅱ. 구성요소
- 핵심 패턴 상세
[Singleton] | [Factory Method] | [Observer]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Singleton | 인스턴스를 하나만 생성하여 전역적으로 공유함 | 정부 청사 (하나만 존재) |
| Factory Method | 객체 생성 처리를 서브 클래스로 분리함 | 맞춤형 제작소 |
| Observer | 상태 변경 시 연관된 객체들에게 자동 통보함 | 유튜브 구독 알림 |
> 요약: 특정 설계 문제를 해결하는 구체적인 객체 지향 기법들임.

## Ⅲ. 절차
- 옵저버 패턴 동작 흐름
[Subject] -> (Register/Detach) -> [Observer List] -> (Notify) -> [Update]

1. 등록: 옵저버 객체들이 서브젝트(주체)에 자신을 등록함.
2. 이벤트 발생: 서브젝트의 내부 상태가 변경되는 사건이 발생함.
3. 알림 전송: 서브젝트가 등록된 모든 옵저버의 update() 메서드를 호출함.
4. 갱신 수행: 각 옵저버는 전달받은 정보를 바탕으로 각자 작업을 수행함.
> 요약: 객체 간의 느슨한 결합을 유지하며 상태 변화를 전파함.

## Ⅳ. 문제점
- 싱글톤의 전역 상태 오염 및 옵저버의 메모리 누수(등록 해제 누락 시).

## Ⅴ. 개선방안
- 멀티스레드 안전성(Thread-safe) 확보 및 약한 참조(Weak Reference) 활용.

## Ⅵ. 전망
- 리액티브 프로그래밍(Reactive Programming) 확산으로 옵저버 패턴 진화 가속.
- 스프링(Spring) 등 프레임워크 수준의 의존성 주입(DI)으로 생성 패턴 대체.
