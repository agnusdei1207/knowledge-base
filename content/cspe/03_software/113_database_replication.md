## 미리 알고가기

- 복제는 동일 데이터 사본을 여러 노드에 유지하는 기술임
- 읽기 분산과 가용성 향상이 대표 목적임
- 복제 지연과 충돌 처리 정책이 구조 선택의 핵심임

## Ⅰ. 개요

- **정의/개념**: 데이터베이스 복제는 한 노드의 변경 내용을 다른 노드로 전달해 동일하거나 거의 동일한 데이터 사본을 유지함으로써 읽기 부하를 분산하고 장애 시 서비스 연속성을 높이는 데이터 가용성 기술임
- **배경/필요성**: 단일 DB는 장애와 읽기 집중에 취약하므로, 운영 중단을 줄이고 조회 확장을 지원할 수 있는 데이터 복제 구조가 필요함

## Ⅱ. 특징

- 읽기 부하 분산과 장애 대응에 효과적임
- 비동기 복제는 성능에 유리하지만 지연과 읽기 불일치를 수반함
- 멀티마스터는 쓰기 가용성이 높지만 충돌 관리가 어렵다
- 장애 전환 절차와 데이터 손실 허용 범위를 함께 설계해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 마스터-슬레이브 | 멀티마스터 |
|:---|:---|:---|
| 쓰기 구조 | 단일 primary | 다중 writable node |
| 강점 | 단순성과 충돌 적음 | 지역 분산과 쓰기 가용성 |
| 한계 | primary 장애 영향 큼 | 충돌 해결 복잡 |
| 적합 환경 | 일반 OLTP 읽기 분산 | 분산 지역 쓰기 요구 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Change Log | 변경 내용을 순서대로 기록해 복제의 기준 원천이 됨 |
| Replica Apply Engine | 로그를 재생해 대상 노드 상태를 맞춤 |
| Lag Monitoring | 원본과 복제본 간 지연을 측정해 읽기 신뢰도를 판단함 |
| Failover Policy | 장애 시 승격과 라우팅 전환 절차를 정의함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 원본 변경 발생  | --> | 로그 전달      | --> | 복제본 반영    | --> | 지연/전환 관리  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **원본 변경 발생**: primary에서 트랜잭션이 커밋됨
2. **로그 전달**: 변경 로그를 복제 채널로 전송함
3. **복제본 반영**: replica가 로그를 재생함
4. **지연과 전환 관리**: lag와 failover 상태를 점검함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 복제 지연을 무시하고 replica를 읽기 원본처럼 사용하면 사용자에게 오래된 데이터가 노출될 수 있음
   - 해결방안: consistency-sensitive read를 primary로 라우팅하고 replication lag와 stale read rate로 검증함
2. 문제: failover 절차가 자동화되지 않으면 장애 시 복구보다 판단 지연이 더 큰 손실로 이어질 수 있음
   - 해결방안: failover drill과 자동 승격 정책을 운영하고 failover recovery time과 split-brain incident count로 검증함
3. 문제: 멀티마스터에서 충돌 규칙이 모호하면 지역별 데이터가 다르게 확정될 수 있음
   - 해결방안: conflict resolution policy를 명문화하고 conflict resolution success rate와 divergence count로 검증함

## Ⅶ. 적용 사례

- 읽기 부하가 큰 전자상거래 DB에서는 읽기 라우팅을 분리하고, replication lag와 stale read rate로 결과를 확인함
- 고가용성 금융 DB에서는 장애 전환 훈련을 운영하고, failover recovery time과 split-brain incident count로 결과를 확인함
- 글로벌 분산 서비스에서는 충돌 정책을 적용하고, conflict resolution success rate와 divergence count로 결과를 확인함

## Ⅷ. 결론

복제 구조의 가치는 사본 수를 늘리는 데 있지 않고 지연과 전환과 충돌을 예측 가능한 운영 규칙으로 통제하는 데 있음.
