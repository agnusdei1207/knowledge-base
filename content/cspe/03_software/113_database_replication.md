## 미리 알고가기

- 복제는 한 데이터베이스의 변경 내용을 다른 노드에도 반영해 같은 데이터 사본을 유지하는 기술임
- 동기 복제는 쓰기 시점에 여러 노드 반영을 기다리고, 비동기 복제는 먼저 쓰고 나중에 따라가게 함
- 장애 조치는 주 노드 장애 시 다른 노드를 승격해 서비스를 이어 가는 절차임

- 스플릿 브레인은 둘 이상의 노드가 동시에 주 노드 역할을 수행해 데이터가 분기되는 장애 상태임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 데이터베이스 복제는 변경 로그·복제 지연·장애 조치를 핵심 축으로 설명함
- 비교표는 단일·다중 주 노드 복제의 쓰기 구조·충돌 처리·적합 환경을 대비함
- 고가용성 DB는 복제 지연·장애 조치 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: 데이터베이스 복제는 한 노드의 변경 로그를 다른 노드에 반영해 데이터 사본을 유지하고 읽기 분산과 장애 전환을 지원하는 기술임
- **배경/필요성**: 단일 DB의 읽기 부하와 장애 위험을 줄이기 위해 복제 지연·장애 조치·쓰기 충돌을 통제하는 복제 구조가 필요함

### 쉽게 이해하기 (학습용)
- 원본 장부의 변경 내용을 여러 지점 장부에 전달해 같은 사본을 유지하는 방식임

## Ⅱ. 특징

- 읽기 부하를 여러 복제본으로 나눌 수 있음
- 장애가 나도 다른 노드를 승격해 복구 시간을 줄일 수 있음
- 비동기 복제는 주 노드 커밋 후 로그를 전달하므로 쓰기 응답은 빠르지만 복제 지연이 발생함
- 다중 주 노드 구조는 쓰기 가용성은 높지만 충돌 처리와 분기 방지가 어려움

### 쉽게 이해하기 (학습용)
- 읽기와 장애 대응은 좋아지지만 사본 반영 지연과 두 원본 충돌을 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 주 노드 복제 | 다중 주 노드 복제 |
|:---|:---|:---|
| 쓰기 구조 | 한 노드만 쓰기를 받음 | 여러 노드가 쓰기를 받을 수 있음 |
| 쓰기 충돌 | 단일 주 노드에서 쓰기 순서 결정 | 여러 주 노드의 동시 쓰기를 감지·병합·거부 |
| 적합 환경 | 온라인 트랜잭션 처리의 읽기 분산과 고가용성 | 지역별 쓰기 분산이 필요한 업무 |

> 요약: 단일 주 노드 복제는 쓰기 순서를 한곳에서 결정하고, 다중 주 노드 복제는 쓰기 분산과 충돌 처리가 필요함.

### 쉽게 이해하기 (학습용)
- 원본 한 곳은 순서가 단순하고, 원본 여러 곳은 지역 쓰기가 빠른 대신 충돌 규칙이 필요함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변경 로그 | 어떤 순서로 어떤 변경이 일어났는지 기록해 복제의 기준이 됨 |
| 복제 반영 엔진 | 로그를 읽어 복제본에 같은 변경을 적용함 |
| 지연 감시 | 원본과 복제본의 차이를 측정해 읽기 신뢰도를 판단함 |
| 장애 조치 정책 | 승격 대상과 전환 순서와 분기 방지 규칙을 정함 |

> 요약: 변경 로그와 반영 엔진이 사본을 갱신하고 지연 감시와 장애 조치 정책이 데이터 신뢰도와 가용성을 통제함.

### 쉽게 이해하기 (학습용)
- 변경 일지, 사본 반영기, 지연 계기판과 원본 교체 규칙으로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
[주 노드 커밋] -> [변경 로그 전송] -> [복제본 재생]
        -> [지연 감시] -> [장애 시 승격·분기 방지]
```

1. **원본 변경 발생**: 주 노드에서 트랜잭션이 커밋됨
2. **로그 전달**: 변경 로그를 복제 채널로 전송함
3. **복제본 반영**: 복제 노드가 로그를 재생해 상태를 맞춤
4. **지연과 전환 관리**: 복제 지연과 장애 조치 상태를 점검함

> 요약: 주 노드의 커밋 로그를 복제본에 전달·재생하고 복제 지연과 장애 전환 상태를 관리함.

### 쉽게 이해하기 (학습용)
- 원본의 변경 일지를 순서대로 사본에 적용하고 얼마나 늦게 따라오는지 측정함

## Ⅵ. 실무 사례

1. 조회 DB는 비동기 복제본으로 읽기를 분산하고 복제 지연·오래된 값 조회 건수를 확인함
2. 결제 DB는 자동 장애 조치와 분기 방지를 적용하고 전환 시간·분기 발생 건수를 확인함

### 쉽게 이해하기 (학습용)
- 읽기 복제본과 대기 주 노드를 두고 장애 때 승격 시간과 데이터 손실 범위를 시험함

## Ⅶ. 결론

- 데이터베이스 복제는 사본의 지연·장애 전환·쓰기 충돌을 운영 규칙으로 통제해야 함
- 복제 지연·데이터 손실 목표·스플릿 브레인 방지 절차를 장애 훈련으로 지속 검증해야 함

### 쉽게 이해하기 (학습용)
- 사본 수보다 원본 교체 때 기록이 빠지거나 두 원본이 생기지 않는지가 더 중요함
