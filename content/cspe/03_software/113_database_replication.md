## 미리 알고가기

- 복제는 한 데이터베이스의 변경 내용을 다른 노드에도 반영해 같은 데이터 사본을 유지하는 기술임
- 동기 복제는 쓰기 시점에 여러 노드 반영을 기다리고, 비동기 복제는 먼저 쓰고 나중에 따라가게 함
- 장애 조치는 주 노드 장애 시 다른 노드를 승격해 서비스를 이어 가는 절차임

## Ⅰ. 개요

- **정의/개념**: 데이터베이스 복제는 한 노드의 변경 내용을 다른 노드로 전달해 동일하거나 거의 동일한 데이터 사본을 유지함으로써 읽기 부하를 분산하고 장애 시 서비스 연속성을 높이는 데이터 가용성 기술임.
- **배경/필요성**: 단일 데이터베이스는 읽기 집중과 장애에 취약하므로, 조회 확장과 장애 대응을 위해 데이터 사본을 운영할 구조가 필요함.

## Ⅱ. 특징

- 읽기 부하를 여러 복제본으로 나눌 수 있음
- 장애가 나도 다른 노드를 승격해 복구 시간을 줄일 수 있음
- 비동기 복제는 성능에 유리하지만 지연 때문에 오래된 데이터를 읽을 수 있음
- 다중 주 노드 구조는 쓰기 가용성은 높지만 충돌 처리와 분기 방지가 어려움

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 주 노드 복제 | 다중 주 노드 복제 |
|:---|:---|:---|
| 쓰기 구조 | 한 노드만 쓰기를 받음 | 여러 노드가 쓰기를 받을 수 있음 |
| 강점 | 구조가 단순하고 충돌 관리가 쉬움 | 지역 분산과 쓰기 가용성에 유리함 |
| 한계 | 주 노드 장애 시 승격 절차가 필요함 | 충돌 해결과 분기 방지 규칙이 복잡함 |
| 잘 맞는 업무 | 일반 온라인 트랜잭션 처리의 읽기 분산과 고가용성 | 지역별 쓰기 분산이 필요한 특수 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 변경 로그 | 어떤 순서로 어떤 변경이 일어났는지 기록해 복제의 기준이 됨 |
| 복제 반영 엔진 | 로그를 읽어 복제본에 같은 변경을 적용함 |
| 지연 감시 | 원본과 복제본의 차이를 측정해 읽기 신뢰도를 판단함 |
| 장애 조치 정책 | 승격 대상과 전환 순서와 분기 방지 규칙을 정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 원본 변경 발생  | --> | 로그 전달      | --> | 복제본 반영    | --> | 지연/전환 관리  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **원본 변경 발생**: 주 노드에서 트랜잭션이 커밋됨
2. **로그 전달**: 변경 로그를 복제 채널로 전송함
3. **복제본 반영**: 복제 노드가 로그를 재생해 상태를 맞춤
4. **지연과 전환 관리**: 복제 지연과 장애 조치 상태를 점검함

## Ⅵ. 실무 적용 및 유의점

1. 읽기 부하가 큰 서비스에서는 복제본으로 조회를 분산할 수 있지만 비동기 지연을 무시하면 오래된 데이터가 노출되므로 복제 지연 시간과 오래된 읽기 발생 건수로 확인함.
2. 고가용성이 중요한 업무에서는 장애 조치 절차가 자동화돼 있어야 하지만 분기 상태가 생기지 않게 해야 하므로 장애 조치 시간과 분기 발생 건수로 확인함.

## Ⅶ. 결론

복제 구조의 가치는 사본 수를 늘리는 데 있지 않고 지연과 장애 전환과 충돌을 예측 가능한 운영 규칙으로 통제하는 데 있음.
