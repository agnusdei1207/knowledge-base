## Ⅰ. 개요
- 정의: 소스 코드를 실행 가능한 산출물로 변환하는 과정을 자동화하는 체계
- 배경: 개발자와 빌드 서버에서 의존성·컴파일·시험·패키징 절차를 같은 방식으로 반복할 필요
- 출제 의도: 빌드 도구(Maven, Gradle)의 특징 비교 및 자동화 프로세스 이해 측정

## Ⅱ. 구성요소
- 구조도
  [Source] -> [Compile] -> [Test] -> [Package] -> [Artifact]
  (Git)     (Compilers)   (JUnit)   (Jar/War)    (Repo)

- 구성요소 표
| 도구 | 설정 방식 | 특징 |
| :--- | :--- | :--- |
| Maven | XML (pom.xml) | 표준 라이프사이클 준수, 정적 구조 |
| Gradle | Groovy/Kotlin DSL | 작업 그래프, 증분 빌드, 빌드 캐시 지원 |
| Ant | XML | 자유도 높으나 절차적, 종속성 관리 부재 |
> 요약: 빌드 설정에 의존성 버전과 컴파일·시험·패키징 단계를 정의하여 동일 절차를 반복 실행함

## Ⅲ. 절차
- 흐름도
  코드 체크아웃 -> 의존성 해결 -> 컴파일 -> 테스트/패키징
- 4단계 설명
1. 코드 체크아웃: 형상 관리 서버로부터 최신 소스 코드를 로컬/빌드 서버로 다운로드
2. 의존성 해결: 중앙 저장소에서 필요한 라이브러리를 자동으로 식별하고 다운로드
3. 컴파일: 소스 코드를 기계어(Bytecode 등)로 변환하고 구문 오류 검사
4. 테스트/패키징: 단위 테스트 수행 후 실행 가능한 형태(JAR/WAR/Docker Image)로 압축
> 요약: 지정된 소스·도구·의존성으로 시험과 패키징을 반복하여 빌드 재현성을 확인함

## Ⅳ. 문제점
- 외부 라이브러리 저장소 장애 시 빌드 불가 (Dependency Hell)
- 프로젝트 규모 확대로 인한 빌드 시간 증가가 전체 개발 사이클의 병목 유발

## Ⅴ. 개선방안
- 전사 프록시 저장소(Nexus/Artifactory) 운영으로 의존성 관리 안정성 확보
- 증분 빌드, 병렬 실행, 빌드 캐시 활용 등 도구별 최적화 기능 적극 도입

## Ⅵ. 전망
- 클라우드 네이티브 환경에 최적화된 컨테이너 빌드 자동화(Buildpacks 등) 확산
- CSF: 빌드 결과의 재현성(Reproducibility) 확보 및 보안 취약점 스캔 통합
