## Ⅰ. 개요
- **정의**: 특정 부서·주제 영역에 최적화된 소규모 분석용 데이터 저장소
- **배경/필요성**: 전사 DW는 범용적이어서 부서별 분석 요구에 대한 쿼리 성능과 접근성이 부족함
- **비유**: 대형 도서관에서 부서별로 자주 보는 책만 모아 놓은 소형 서가와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DW와 마트 관계 이해 | 종속형 vs 독립형 마트, 스타 스키마 적용 | DW 없는 독립형 마트의 데이터 사일로 위험 |

> 요약: 부서·주제별 분석 요구에 최적화된 목적형 데이터 저장소임

## Ⅱ. 구성요소
```text
[전사 DW] --> [ETL/뷰] --> [데이터 마트] --> [부서 리포트/대시보드]
                               |
                        [스타 스키마]
                          /       \
                   [팩트 테이블] [디멘전 테이블]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 팩트 테이블 | 측정값(매출액·건수 등)을 저장하는 중심 테이블 | 거래 전표 |
| 디멘전 테이블 | 분석 축(시간·제품·지역 등)을 정의하는 참조 테이블 | 분류 기준표 |
| ETL/뷰 | DW에서 마트로 데이터를 추출·적재하는 파이프라인 | 서가 진열 담당 |
| 대시보드 | 마트 데이터를 시각화하여 부서 사용자에 제공하는 UI | 부서 게시판 |

> 요약: DW에서 추출한 데이터를 스타 스키마로 구성하여 부서별 분석에 제공하는 구조임

## Ⅲ. 절차
```text
요구 분석 --> DW 데이터 추출 --> 스키마 설계/적재 --> 분석 활용
```
- 1단계: 요구 분석 — 부서별 분석 주제·지표·차원을 정의함
- 2단계: DW 데이터 추출 — 전사 DW에서 해당 주제 영역 데이터를 추출함
- 3단계: 스키마 설계/적재 — 스타 스키마로 모델링하고 마트에 적재함
- 4단계: 분석 활용 — BI 도구(160 참조)를 통해 리포트·대시보드를 생성함

> 요약: 요구분석-추출-적재-활용의 4단계로 부서 맞춤형 분석 환경을 구축함

## Ⅳ. 문제점
- 데이터 사일로: 독립형 마트 난립 시 마트 간 지표 불일치 — 전사 정합성 저하
- 중복 저장: DW 데이터를 마트에 재복제 — 저장 비용 증가 및 갱신 부담
- 유지보수 부담: 마트별 ETL 관리 필요 — 변경 시 영향 범위 파악 곤란

> 요약: 데이터 사일로, 중복 저장, 유지보수 부담이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 종속형 마트 패턴 채택으로 DW 기반 단일 원천 유지
2. 중기: 매터리얼라이즈드 뷰 활용으로 물리 복제 대신 논리적 마트 구성
3. 장기: 데이터 가상화(155 참조) 기반 온디맨드 마트로 전환하여 중복 제거

> 요약: 종속형 패턴, 논리적 마트, 가상화 전환으로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: 클라우드 DW의 성능 향상으로 별도 마트 없이 DW 직접 분석 추세 확산
- 기술사적 판단: 셀프서비스 BI 확산과 함께 사용자 주도 가상 마트 패턴 증가
- 기술사 제언: 마트 설계 시 전사 DW 종속형을 원칙으로 하여 데이터 정합성을 확보할 필요
