## 미리 알고가기

- AIOps는 운영 텔레메트리와 변경·토폴로지 정보를 분석해 이상·사건 관계·대응 후보를 제시함
- 이상 탐지는 과거 또는 동적 기준에서 벗어난 시계열·로그·이벤트를 식별함
- 이벤트 상관은 시간·서비스 의존성·공통 변경을 기준으로 여러 경보를 하나의 사건 후보로 묶음
- 토폴로지는 서비스·Pod·노드·데이터베이스의 의존 관계와 변경 영향을 나타냄
- Runbook은 확인·완화·복구 동작과 승인 조건을 정의한 운영 절차임
- 학습 데이터 편향과 서비스 변경은 오탐·미탐을 만들 수 있어 피드백과 모델 검증이 필요함

## 작성 근거(검토용)

- AIOps는 데이터 통합, 이상 탐지, 이벤트 상관, 토폴로지 문맥, 자동화·피드백을 핵심 축으로 설명함
- 비교표는 규칙 기반 운영 분석과 AIOps의 기준·문맥·학습·검증 차이를 대비함
- 절차는 텔레메트리 정규화부터 이상·사건 후보 생성, 추천·승인·자동 조치, 결과 학습으로 이어짐

## Ⅰ. 개요

- **정의/개념**: AIOps는 메트릭·로그·트레이스·이벤트·변경 정보를 통합하고 통계·ML로 이상과 사건 관계를 분석해 운영 대응을 지원하는 방식임
- **배경/필요성**: 동적 클라우드 환경에서 중복 경보와 서비스 의존 관계를 사람이 모두 대조하기 어려워 운영 데이터의 상관·우선순위 분석이 필요함

## Ⅱ. 특징

- 이종 운영 데이터를 공통 시간·리소스·서비스 문맥으로 정규화함
- 정적 임계치와 함께 시계열·로그 패턴의 동적 기준으로 이상 후보를 탐지함
- 토폴로지·변경·시간 관계로 중복 경보를 사건 후보에 묶고 영향 범위를 계산함
- 신뢰도·위험도에 따라 추천·승인 요청·자동 실행을 나누고 조치 결과를 피드백함

## Ⅲ. 종류 및 비교

| 판단 기준 | 규칙 기반 운영 분석 | AIOps |
|:---|:---|:---|
| 탐지 기준 | 고정 임계치·명시 규칙 | 통계 기준·학습 패턴·규칙 조합 |
| 이벤트 결합 | 사전 정의 키·시간 창으로 묶음 | 시간·토폴로지·변경 문맥으로 상관 |
| 환경 변화 | 규칙을 사람이 수정 | 모델 재학습·기준 갱신과 검증 필요 |
| 결과 형태 | 조건에 맞는 경보·조치 실행 | 이상 점수·사건 후보·영향·조치 추천 |
| 검증 대상 | 규칙 적중·누락과 실행 오류 | 정밀도·재현율·드리프트·자동화 성공률 |
| 적합 조건 | 원인과 임계치가 고정된 운영 | 신호량이 많고 의존 관계가 변하는 운영 |

> 요약: AIOps는 운영 신호를 토폴로지·변경 문맥과 연결해 이상과 사건 후보를 만들고 결과를 검증함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 수집기 | 메트릭·로그·트레이스·경보·변경 이벤트를 수집함 |
| 정규화·품질 계층 | 시간·리소스 ID·서비스 속성을 맞추고 누락·중복을 처리함 |
| 토폴로지·변경 저장소 | 서비스 의존 관계와 배포·설정 변경 이력을 제공함 |
| 분석 엔진 | 이상 탐지·패턴 분류·이벤트 상관·영향 추정을 수행함 |
| 사건·우선순위 계층 | 경보를 사건 후보로 묶고 신뢰도·사용자 영향으로 정렬함 |
| 자동화·피드백 | 승인된 Runbook을 실행하고 결과를 모델·규칙 개선에 반영함 |

```text
운영 신호·변경 -> 정규화 -> 이상 탐지·이벤트 상관 -> 사건 우선순위
                      ^                |                    |
                 토폴로지 -------------+                    +-> Runbook·피드백
```

> 요약: 정규화한 운영 신호를 토폴로지·변경 이력과 결합해 사건 후보와 대응 우선순위를 생성함.

## Ⅴ. 원리 및 절차 흐름도

```text
신호 수집 -> 정규화·보강 -> 이상 탐지 -> 이벤트 상관 -> 신뢰도 판정 -> 조치 -> 피드백
```

1. **신호 수집**: 관측·ITSM·배포 시스템에서 운영 데이터를 가져옴
2. **정규화·보강**: 시간·리소스 ID를 맞추고 토폴로지·변경 정보를 연결함
3. **이상 탐지**: 규칙·통계·ML이 기준을 벗어난 신호에 이상 점수를 부여함
4. **이벤트 상관**: 시간·의존 관계·공통 변경으로 경보를 사건 후보에 묶음
5. **판정·조치**: 신뢰도와 위험도에 따라 추천·승인 요청·자동 실행으로 분기함
6. **피드백**: 실제 원인과 조치 결과를 모델·규칙·자동화 정책에 반영함

> 요약: 운영 신호를 문맥화해 사건 후보를 만들고 신뢰도에 맞는 조치와 학습 피드백을 수행함.

## Ⅵ. 실무 사례

1. Kubernetes 경보 분석은 토폴로지·배포 변경으로 사건을 묶고 중복 감소율·경보 묶음 정밀도를 확인함
2. 스토리지 이상 탐지는 시계열 모델과 승인 Runbook을 적용하고 오탐률·복구 성공률을 확인함

## Ⅶ. 결론

- AIOps는 데이터 품질·토폴로지·모델 정확도를 검증하고 조치 위험에 따라 사람 승인과 자동화를 구분함
