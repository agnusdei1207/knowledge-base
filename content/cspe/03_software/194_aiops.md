# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 인공지능(AI)과 머신러닝(ML)을 활용하여 IT 운영을 자동화하고 지능화하는 기술 체계
- **왜 필요한가**: 클라우드와 MSA로 시스템이 복잡해지면서 하루 수백만 건의 경고(Alert)와 로그가 발생해 사람이 직접 분석하고 대응하는 것이 불가능해짐
- **핵심 직관**: 인간 운영자가 CCTV 수백 대를 보며 범인을 찾는 대신, AI가 패턴을 분석해 "저기서 문제가 터질 것 같습니다"라고 짚어주고 원인까지 알려주는 지능형 관제 시스템이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Alert Fatigue (경고 피로) | 의미 없는 알람이 너무 많이 와서 진짜 장애를 놓치는 현상 | "양치기 소년의 거짓말 알람" |
| Root Cause Analysis (RCA) | 장애를 유발한 최초의 근본 원인을 추적하여 찾아내는 분석 | "도미노가 쓰러진 첫 번째 블록 찾기" |
| Anomaly Detection (이상 탐지) | 정상적인 패턴을 벗어나는 비정상 트래픽이나 리소스 급증 탐지 | "평소와 다른 이상 행동 발견" |

## 깊이 이해
- **배경·문제의식**: 시스템 장애 발생 시 쏟아지는 이벤트 폭풍(Event Storm) 속에서 운영자는 어디서부터 손대야 할지 패닉에 빠진다. 룰(Rule) 기반 모니터링은 정해진 임계치만 감지하므로 미세한 이상 징후를 놓친다.
- **작동 원리**: AIOps 플랫폼은 IT 환경의 방대한 데이터(로그, 메트릭, 트레이스)를 빅데이터 기술로 통합 수집한다. 머신러닝 알고리즘이 이 데이터를 학습해 노이즈를 제거하고 유효한 이벤트를 상관분석하여 묶는다. 이를 통해 장애 근본 원인(RCA)을 도출하고, 과거 패턴을 바탕으로 장애를 사전 예측하거나 스크립트를 통해 자동 복구(Auto Remediation)를 수행한다.
- **비유**: 베테랑 의사 수천 명의 지식을 뇌에 담고 있는 로봇 닥터다. 환자(서버)의 미세한 맥박 변화(로그)만 보고도 내일 심장마비(장애)가 올 것을 예측해 미리 처방을 내린다.
- **구체 예시**: 블랙프라이데이 트래픽 급증 시 CPU 사용량이 서서히 증가하면, 과거 룰 기반은 90% 도달 시점에 알림을 보냈으나, AIOps는 70% 시점에 증가 기울기를 분석하여 30분 뒤 장애 발생을 예측하고 자동으로 컨테이너를 스케일아웃한다.
- **흔한 오해·주의점**: AIOps를 도입하면 즉시 100% 자동 복구가 될 것이라 기대하지만, 초기에는 데이터 정제와 ML 모델 학습(노이즈 제거)에 많은 시간이 소요되며, 신뢰성이 쌓이기 전까지는 의사결정 지원(추천) 수준에서 시작해야 한다.

## 연결 개념
- SRE — AIOps를 도구로 활용해 신뢰성 극대화
- Observability (관측성) — AIOps의 입력 데이터(로그, 메트릭, 트레이스) 제공 기반
- MLOps — AIOps 모델 자체의 배포와 파이프라인 관리

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AIOps는 빅데이터와 머신러닝을 IT 운영 데이터에 적용하여 실시간 인사이트 도출 및 자동 복구를 수행하는 지능형 운영 체계임
> 2. **가치**: 이벤트 노이즈 축소, 장애 근본 원인 분석(RCA) 시간 단축, 사후 대응에서 사전 예측 모델로의 패러다임 전환 제공
> 3. **판단 포인트**: 성공적인 AIOps 적용을 위해서는 파편화된 IT 데이터를 하나로 모으는 데이터 통합(Data Lake) 인프라가 선행되어야 함

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기존 모니터링의 한계 극복 및 AI 기반 자동화 이해 | 관측성 3요소 통합 수집, 머신러닝 이상 탐지, RCA 자동화 | 단순 챗봇이나 대시보드 시각화로 한정 단정 |

> 요약: AIOps는 통합 수집된 방대한 운영 데이터를 ML로 분석해 장애 원인을 파악하고 대응을 자동화하는 진화된 운영 플랫폼임

---

## Ⅰ. 개요 및 필요성

- 개요: 방대한 IT 운영 데이터에 인공지능과 머신러닝 기법을 적용하여 이벤트를 분석, 장애를 예측하고 자동 복구를 지원하는 솔루션 플랫폼임
- 배경: 클라우드 네이티브 아키텍처 확산으로 폭증한 로그 및 이벤트 경고 피로(Alert Fatigue) 극대화
- 필요성: 임계치 기반의 정적 모니터링 한계를 극복하고 MTTR(평균 복구 시간) 단축 및 지능형 사전 예방 체계 확보 절실

---

## Ⅱ. 구조 및 구성요소

```text
데이터 소스 수집 -> 빅데이터 플랫폼 적재 -> ML 기반 분석 -> 통찰 및 자동 복구
                   |                         |
                   +-> 관측성 데이터 풀      +-> 노이즈 축소 / RCA
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Data Ingestion | 로그, 메트릭, 분산 트레이스 등 멀티 소스 통합 수집 | Kafka, Fluentd 연동 |
| ML Analytics | 이상 탐지, 패턴 인식, 이벤트 상관분석 수행 | 노이즈 필터링 엔진 탑재 |
| Automation | 분석된 Root Cause 기반 런북(Runbook) 자동 실행 | 스크립트 기반 자동 복구 |

> 요약: AIOps 플랫폼은 데이터를 통합 수집하고 ML로 분석하여 근본 원인을 찾고 런북 기반으로 자동 복구함

---

## Ⅲ. 동작원리 및 흐름도

```text
관측 데이터 수집 -> 노이즈 제거 및 상관분석 -> 근본 원인 도출 -> 런북 실행 복구
```

- 1단계 [통합 수집]: 애플리케이션 및 인프라의 파편화된 데이터를 실시간 스트리밍으로 수집
- 2단계 [상관 분석]: ML 알고리즘을 통해 수만 건의 중복 이벤트를 그룹화하여 노이즈 축소
- 3단계 [원인 식별]: 토폴로지 맵을 기반으로 장애 전파 경로를 추적하여 근본 원인(Root Cause) 식별
- 4단계 [자동 복구]: 식별된 문제에 매핑된 자동화 런북 스크립트 호출로 시스템 자가 치유 실행

> 요약: 방대한 이벤트에서 노이즈를 제거하고 핵심 원인을 도출해 사전 정의된 절차대로 자동 복구를 수행함

---

## Ⅳ. 특징
- 예방적 유지보수: 사후 대응(Reactive) 방식에서 벗어나 시계열 예측 모델을 통해 장애 사전 차단(Proactive)
- 알람 피로 억제: 중복되거나 연관된 경고 메시지를 하나의 인시던트로 병합하여 운영자의 분석 피로도 획기적 감소
- 동적 베이스라인: 고정된 임계값이 아니라 시간대, 요일 등 과거 패턴을 학습한 동적 기준선을 적용해 오탐 최소화

---

## Ⅴ. 심화 비교 및 적용 판단

| 운영 방식 | 전통적 IT 운영 (ITOM) | AIOps 기반 운영 | 선택 기준 |
|:---|:---|:---|:---|
| 경고 발생 기준 | 정적 임계치 룰 설정 | ML 기반 동적 베이스라인 학습 | 비즈니스 트래픽 변동성 |
| 이벤트 처리 | 개별 알람 수동 분석 | 이벤트 상관분석 및 자동 병합 | 인시던트 발생량 |
| 장애 복구 | MTTR 장기 소요 (사후) | 근본원인 도출 및 자동화 (사전/실시간) | 요구 가용성 수준 |

> 요약: AIOps는 수동 룰 기반 관제에서 벗어나 데이터 학습 기반의 동적 통제와 원인 분석 자동화를 제공함

**리스크·대응 (기본은 불릿):**
- 데이터 사일로 한계: 부서별, 툴별 파편화된 데이터로 ML 정확도 하락 → Observability 기반의 통합 데이터 레이크 확보 선행 (지표: 통합 수집 커버리지 비율)
- 블랙박스 의사결정: AI의 복구 추천 근거를 운영자가 신뢰하지 못함 → 설명 가능한 AI(XAI) 기술 적용 및 초기엔 추천(Advisory) 모드로 운영 (지표: AI 제안 수락률)

**도입 후 점검 지표 (기본은 불릿):**
- 노이즈 감소율: 초기 수집 이벤트 대비 운영자에게 노출된 최종 인시던트 건수 압축 비율 — 알람 시스템 분석
- MTTR 단축: 장애 인지부터 실제 근본 원인 파악 및 시스템 복구까지 걸리는 총 소요 시간 — ITSM 티켓 데이터 확인

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 파운데이션: 로그, 메트릭, 트레이스를 단일 플랫폼(예: Elasticsearch)으로 모아 ML 엔진이 학습할 통합 데이터 레이크 확보
2. 토폴로지 자동 구성: 분산 트레이싱을 활용하여 서비스 간 의존성 맵을 실시간 갱신하고 장애 파급 범위 식별 지원
3. 점진적 자동화: 1단계는 단순 이상 탐지 경고, 2단계는 RCA 추천, 3단계는 검증된 패턴에 대해 런북 자동 복구 실행으로 단계적 권한 위임

**결론 (2줄):**
- 기술사 판단: AIOps의 성패는 고도화된 알고리즘 자체보다, 양질의 관측성 데이터를 한 곳으로 모으는 데이터 거버넌스 역량에 좌우됨
- 향후 방향: 생성형 AI(LLM)와 결합하여 운영자가 자연어로 로그를 질의하고 복구 스크립트까지 자동 생성받는 초자동화(Hyper-Automation) 관제 체계로 진화
