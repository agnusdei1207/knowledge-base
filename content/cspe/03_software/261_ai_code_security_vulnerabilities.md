## Ⅰ. 개요
- **정의**: AI 생성 코드에 내재된 보안 결함이 런타임에 악용 가능한 공격 표면을 형성하는 현상
- **배경/필요성**: LLM 기반 코드 생성 도구 보편화로 검증 없이 배포되는 코드 비율이 증가하여 취약점 유입 경로가 확대됨
- **비유**: AI가 쓴 코드는 자동 번역문과 유사—문법은 맞지만 문맥상 오역(취약점)이 숨어 있음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 코드 생성의 보안 리스크 이해 | CWE 유형별 취약점 분류 | 단순 나열이 아닌 원인-결과 연결 필요 |

> 요약: AI 생성 코드의 보안 취약점은 검증 부재 시 공격 표면을 확대하는 위험 요소임

## Ⅱ. 구성요소
```text
[AI Code Generator] --생성--> [Raw Code]
        |                        |
        v                        v
[Training Data Bias]    [Static Analysis] --탐지--> [Vulnerability DB]
        |                        |
        v                        v
[Hallucinated API]      [Dynamic Testing] --검증--> [Remediation]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Training Data Bias | 학습 데이터에 포함된 취약 패턴이 생성 코드에 재현됨 | 오염된 교재로 배운 학생 |
| Hallucinated API | 존재하지 않는 함수·라이브러리를 호출하여 의존성 공격에 노출됨 | 없는 약을 처방하는 의사 |
| Static Analysis | 소스 코드 패턴 매칭으로 CWE 항목 탐지함 | 문서 교정기 |
| Vulnerability DB | 알려진 취약점 패턴을 축적하여 비교 기준 제공함 | 과거 사고 사례집 |

> 요약: 학습 편향과 허위 API가 취약점 원인이며, 정적·동적 분석이 탐지 수단임

## Ⅲ. 절차
```text
코드 생성 --> 정적 분석 --> 동적 테스트 --> 수정/배포
    |            |              |              |
    v            v              v              v
  LLM출력    패턴매칭       퍼징/DAST      패치적용
```
- 1단계: LLM이 프롬프트 기반으로 코드를 생성함
- 2단계: SAST 도구가 CWE 기준으로 정적 패턴을 탐지함
- 3단계: DAST·퍼징으로 런타임 취약점을 검증함
- 4단계: 탐지된 취약점을 수정하고 보안 게이트 통과 후 배포함

> 요약: 생성-분석-검증-수정의 4단계로 AI 코드 보안을 확보함

## Ⅳ. 문제점
- 학습 데이터 오염: 공개 저장소의 취약 코드가 학습에 포함됨 — 생성 코드에 동일 취약점이 재현됨
- 검증 우회 배포: 개발 속도 우선으로 보안 게이트를 생략함 — 취약 코드가 운영 환경에 유입됨
- 허위 의존성 공격: 존재하지 않는 패키지명을 공격자가 선점함 — 공급망 공격 경로가 생성됨

> 요약: 데이터 오염·검증 생략·허위 의존성이 AI 코드의 3대 보안 위협임

## Ⅴ. 개선방안
1. 단기: 학습 데이터 큐레이션 및 취약 패턴 필터링 파이프라인 구축
2. 중기: CI/CD에 AI 코드 전용 SAST/DAST 게이트를 필수 단계로 통합
3. 장기: 패키지 네임스페이스 검증 체계 및 SBOM 기반 공급망 보안 자동화

> 요약: 데이터 정제-보안 게이트 통합-공급망 검증으로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: AI 코드 생성 시 실시간 보안 검증이 내장된 Secure-by-Design 모델로 진화함
- 기술사적 판단: AI 코드 보안은 DevSecOps의 새로운 필수 영역으로 자리잡을 것임
- 기술사 제언: 조직 내 AI 코드 보안 정책 수립과 자동화 도구 도입을 선제적으로 추진할 필요
