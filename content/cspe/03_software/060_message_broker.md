## Ⅰ. 개요
- 정의: 서비스 간 비동기 데이터 교환을 위해 메시지를 수신, 저장, 전달하는 중간 매개 시스템.
- 출제 의도: 시스템 간 결합도 완화, 부하 분산, 데이터 유실 방지를 위한 메시징 기술 비교 역량 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Producer ] --(Send)--> [ Message Broker (Queue/Topic) ] --(Deliver)--> [ Consumer ]
                              (Store & Route)
- 구성요소 표
| 특성 | RabbitMQ | Apache Kafka |
| :--- | :--- | :--- |
| 모델 | 메시지 큐 (Smart Broker, Dumb Consumer) | 분산 로그 (Dumb Broker, Smart Consumer) |
| 주 용도 | 복잡한 라우팅, 실시간 개별 메시지 처리 | 대용량 로그 스트리밍, 이벤트 소싱 |
| 영속성 | 처리 완료 시 메시지 삭제가 기본 | 설정된 기간 동안 데이터 영구 보관 가능 |
> 요약: RabbitMQ는 유연한 전달, Kafka는 고성능 저장 및 재처리에 특화됨.

## Ⅲ. 절차
- ASCII 흐름도
  [발행(Publish)] -> [저장(Persistence)] -> [라우팅(Routing)] -> [소비(Consume)]
- 4단계 설명
1. 발행자가 전송하려는 데이터를 특정 큐나 토픽으로 전송함.
2. 브로커는 수신된 메시지를 메모리나 디스크에 안전하게 적재함.
3. 교환기(Exchange)나 파티션 규칙에 따라 적절한 수신처를 결정함.
4. 구독자가 준비되었을 때 메시지를 가져가거나 브로커가 밀어 넣어 처리함.
> 요약: 송신자와 수신자가 서로를 몰라도 통신 가능한 '비동기 통신' 구현함.

## Ⅳ. 문제점
- 운영 복잡성: 클러스터 구성 및 주키퍼(Zookeeper) 등 관리 포인트가 많아 운영 부담큼.
- 지연 발생: 메시지 양 급증 시 큐에 쌓이는 백로그(Backlog)로 인해 처리 지연 발생함.

## Ⅴ. 개선방안
- 고가용성 구성: 데이터를 여러 노드에 복제(Replication)하여 노드 장애 시 유실 방지함.
- 오토스케일링: 컨슈머 그룹을 동적으로 확장하여 백로그를 빠르게 소진함.

## Ⅵ. 전망
- 'Cloud Managed Message Service' 도입을 통해 인프라 관리 부담을 줄이는 추세임.
- 실시간 데이터 분석(Stream Processing)과 결합하여 '데이터 중심 아키텍처'의 핵심으로 부상함.
- 서버리스 이벤트 기반 아키텍처(EDA)의 이벤트 버스 역할을 수행하며 통합 접점 강화됨.
