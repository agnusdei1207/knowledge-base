## Ⅰ. 개요
- 정의: AI와 자동화 기술의 발전에 따라 소프트웨어 개발 패러다임이 진화하는 방향임
- 배경: 개발 생산성 한계 극복 및 SW 복잡도 증가에 따른 지능적 관리 도구 필요성 대두
- 출제 의도: AI-Native 개발, 로우코드/노코드, 자율 운영 시스템 등 미래상 통찰력 평가

## Ⅱ. 구성요소
- ASCII 구조도
  [Traditional SE] --(AI Integration)--> [Next-Gen SE]
         |                                  |
    (Human-Led)                     (AI-Augmented/Autonomous)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| AI 코딩 어시스턴트 | 코드 자동 생성 및 버그 수정 제안 도구 | 내비게이션 |
| 로우코드/노코드 | 최소한의 코딩으로 앱을 빌드하는 플랫폼 | 기성품 조립 |
| 자가 치유(Self-healing) | 장애를 스스로 탐지하고 복구하는 아키텍처 | 자율 주행 |
> 요약: 사람이 주도하던 개발에서 AI와 협업하거나 AI가 주도하는 자율 개발로 전이함

## Ⅲ. 절차
- ASCII 흐름도
  Manual -> Assisted -> Augmented -> Autonomous
- 4단계 설명
1. Manual: 개발자가 모든 설계와 구현을 직접 수행하는 단계임
2. Assisted: 린팅, 자동 완성 등 단순 편의 기능을 활용하는 단계임
3. Augmented: AI가 아키텍처 추천 및 대량의 코드를 생성하는 단계임
4. Autonomous: 요구사항 정의 시 AI가 설계부터 배포까지 자율 수행함
> 요약: 수동 개발에서 보조-증강을 거쳐 자율적인 소프트웨어 생명주기로 진화함

## Ⅳ. 문제점
- 원인이 명시된 문제/한계: AI 생성 코드의 보안 취약점 및 저작권 분쟁, 개발자의 역량 퇴보 우려됨

## Ⅴ. 개선방안
- Ⅳ의 문제에 대응하는 방안: AI 윤리 가이드라인 수립 및 고난도 아키텍처 설계 역량 강화함

## Ⅵ. 전망
- 발전 방향: 소프트웨어 엔지니어링의 역할이 '구현'에서 '조율 및 프롬프트 설계'로 변모
- CSF: AI를 도구로 다루는 능력과 복잡한 도메인 논리를 구조화하는 추상화 역량이 핵심임
