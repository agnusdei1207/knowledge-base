## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 하드웨어 자원을 효율적으로 관리하고 사용자에게 인터페이스를 제공하는 핵심 시스템 S/W |
| 배경 | 하드웨어 복잡도 증가, 자원 공유의 효율성 및 보안성 확보 필요 |
| 출제 의도 | 커널 구조(Monolithic/Micro) 및 OS의 5대 관리 기능 이해 측정 |

## Ⅱ. 구성요소
```text
+---------------------------------------+
|            User Interface             |
+---------------------------------------+
|              System Call              |
+---------------------------------------+
|  Process | Memory | File | I/O (Kernel) |
+---------------------------------------+
|           Hardware (CPU/RAM)          |
+---------------------------------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 커널 (Kernel) | 프로세스 관리, 메모리 제어 등 OS 핵심 기능 수행 | 정부 부처 |
| 인터페이스 | CLI, GUI 등 사용자와 OS 간의 소통 창구 | 민원 창구 |
| 시스템 콜 | 커널 서비스를 요청하기 위한 프로그래밍 인터페이스 | 민원 신청서 |
> 요약: 커널은 하드웨어를 제어하고, 시스템 콜은 사용자 요청을 커널에 전달함.

## Ⅲ. 절차
```text
(User Mode)      (Kernel Mode)
App Request ----> System Call ----> Kernel Task ----> H/W Access
     ^                                                  |
     +------------------- Response ---------------------+
```
1. 사용자 모드 실행: 응용 프로그램이 사용자 영역에서 일반 명령 수행.
2. 트랩(Trap) 발생: 특권 명령 필요 시 시스템 콜 호출 및 모드 비트 전환(1->0).
3. 커널 모드 서비스: 커널이 요청된 작업(I/O, 메모리 등)을 직접 처리.
4. 사용자 모드 복귀: 결과 반환 후 모드 비트 원복(0->1) 및 앱 제어권 이양.
> 요약: 모드 전환을 통해 하드웨어를 보호하고 안정적인 서비스 수행을 보장함.

## Ⅳ. 문제점
- 커널 기능 비대화로 인한 단일 장애 지점(SPOF) 발생 및 유지보수 어려움.
- 잦은 시스템 콜 호출에 따른 컨텍스트 스위칭 오버헤드로 성능 저하 발생.

## Ⅴ. 개선방안
- 계층형 커널 또는 마이크로 커널 구조 도입을 통한 모듈화 및 안정성 강화.
- Zero-copy 기술 및 User-level Driver 적용으로 모드 전환 비용 최소화.

## Ⅵ. 전망
- 지능형 OS: AI 칩(NPU) 최적 스케줄링 및 자원 예측 관리 기능 탑재 가속화.
- 클라우드 네이티브: 경량화된 MicroOS 및 컨테이너 전용 OS 채택 확대.
