## Ⅰ. 개요
- 정의: 서버로부터 초기 한 페이지를 로드한 뒤, 데이터만 동적으로 갱신하는 웹 애플리케이션
- 배경: 모바일 앱과 같은 매끄러운 UX와 서버 부하 경감 필요성
| 구분 | 내용 |
|------|------|
| 출제 의도 | CSR(Client Side Rendering) 방식의 장단점 및 상태 관리 아키텍처 파악 |

## Ⅱ. 구성요소
  User -> [ Client App (JS) ] <-> [ API Server ]
  (No Full Page Reload)
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| Routing | URL 변경 시 페이지 이동 없이 컴포넌트 전환 | 내비게이션 |
| State | 앱 전역에서 관리되는 데이터 상태 | 장부 |
| Virtual DOM | 변경 사항만 효율적으로 반영하는 가상 트리 | 설계 도면 |
> 요약: 클라이언트 중심의 렌더링과 데이터 통신 기반 아키텍처

## Ⅲ. 절차
  Initial Load -> Bootstrapping -> Data Fetch -> Patch DOM
1. Initial Load: 최소한의 HTML과 대규모 JS 번들 다운로드
2. Hydration: JS가 실행되며 정적 요소에 이벤트 바인딩
3. Interaction: 사용자 조작 시 API 서버로 데이터 요청
4. Update: 변경된 데이터만 Virtual DOM을 거쳐 부분 렌더링
> 요약: 초기 로드 후 필요한 부분만 갱신하여 빠른 반응 속도 제공

## Ⅳ. 문제점
- 초기 로딩 속도(FCP) 저하 및 검색 엔진 최적화(SEO)의 어려움
- 클라이언트 사이드 비즈니스 로직 노출 및 보안 취약성

## Ⅴ. 개선방안
- SSR(Server Side Rendering) 또는 SSG 결합(Next.js 등) 적용
- 코드 분할(Code Splitting) 및 트리 쉐이킹으로 번들 크기 최적화

## Ⅵ. 전망
- Micro Frontend 도입을 통한 거대 SPA 모듈화 및 Edge computing 기반 렌더링 가속
