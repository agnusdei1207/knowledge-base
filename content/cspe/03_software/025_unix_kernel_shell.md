## 미리 알고가기

- 커널은 하드웨어 자원과 시스템 호출을 관리하는 운영체제 핵심부임
- 쉘은 사용자의 명령을 해석해 프로그램 실행으로 연결하는 인터페이스임
- 파일시스템은 데이터를 파일과 디렉터리 구조로 조직하는 저장 계층임
- 시스템 호출(System Call): 사용자 공간 프로그램이 커널 기능을 요청하는 표준 인터페이스임
- 파이프(Pipe): 한 프로세스의 출력을 다른 프로세스의 입력으로 연결하는 통신 방식임

## 작성 근거(검토용)

- 커널·쉘·파일시스템을 역할·실행 계층·입출력 인터페이스로 구분함
- 명령 입력·파싱·시스템 호출·프로세스 및 파일 처리 순서를 실제 실행 흐름으로 유지함
- 운영 자동화와 다중 사용자 권한을 쉘·파일시스템의 대표 사례로 연결함

## Ⅰ. 개요

- **정의/개념**: UNIX 시스템은 자원 관리와 보호를 담당하는 커널, 사용자 명령 해석과 실행을 담당하는 쉘, 데이터를 계층적으로 저장하고 접근하게 하는 파일시스템의 3요소로 구성되는 운영체제 구조임
- **배경/필요성**: 사용자 명령·자원 제어·영속 저장의 책임을 분리하기 위해 커널·쉘·파일시스템 구조가 필요함

## Ⅱ. 특징

- 커널 공간과 사용자 공간을 분리해 시스템 호출 경계에서 권한을 검사함
- 쉘은 명령·파이프·리다이렉션·스크립트로 프로그램 실행과 데이터 전달을 조합함
- 파일시스템은 장치·파이프 등 여러 자원을 파일 인터페이스로 다루는 UNIX 구조를 지원함
- 쉘과 응용은 시스템 호출·파일 인터페이스로 커널 기능을 조합함

## Ⅲ. 종류 및 비교

| 판단 기준 | 커널 | 쉘 | 파일시스템 |
|:---|:---|:---|:---|
| 역할 | 자원 관리와 시스템 호출 처리 | 명령 해석과 프로그램 실행 연결 | 데이터·메타데이터 저장과 접근 제어 |
| 실행 계층 | 커널 공간(특권 모드) | 사용자 공간 | 커널 내부 핵심 계층 |
| 입출력 인터페이스 | 시스템 호출·인터럽트로 자원 처리 결과 반환 | 명령어·스크립트 입력, 프로세스 실행·파이프라인 출력 | 경로·파일 I/O 요청 입력, 데이터·메타데이터 출력 |

> 요약: 쉘은 명령을 해석하고, 커널은 시스템 호출로 자원을 제어하며, 파일시스템은 데이터와 메타데이터를 저장함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 커널 핵심부 | 프로세스·메모리·장치·시스템 호출을 관리함 |
| 쉘 인터페이스 | 명령 파싱·환경 변수·파이프·리다이렉션을 처리함 |
| 파일시스템 계층 | 파일·디렉터리·권한·저장 블록을 관리함 |
| 시스템 호출 경계 | 쉘·응용의 요청을 커널 기능과 연결하고 권한을 검사함 |

> 요약: 쉘과 응용은 시스템 호출 경계를 거쳐 커널과 파일시스템의 자원 기능을 사용함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령 입력      | --> | 쉘 해석        | --> | 시스템 호출    | --> | 파일/프로세스 처리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령 입력**: 사용자가 쉘에 명령이나 스크립트를 입력함
2. **쉘 해석**: 쉘이 명령을 파싱하고 프로그램과 파이프와 리다이렉션을 구성함
3. **시스템 호출**: 필요한 파일 접근과 프로세스 생성과 장치 사용을 커널에 요청함
4. **파일 및 프로세스 처리**: 커널과 파일시스템이 실제 자원 작업을 수행하고 결과를 반환함

## Ⅵ. 실무 사례

1. 서버 운영 자동화는 쉘 스크립트 공통 함수와 정적 검사를 적용하고 실행 실패율과 배포 성공률을 확인함
2. 다중 사용자 UNIX는 파일 권한 기준을 적용하고 권한 편차 건수와 접근 위반 수를 확인함

## Ⅶ. 결론

- UNIX는 커널의 자원 제어·쉘의 명령 해석·파일시스템의 영속 저장을 시스템 호출과 파일 인터페이스로 연결함
