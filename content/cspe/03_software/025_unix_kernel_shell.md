## 미리 알고가기

- 커널은 하드웨어 자원과 시스템 호출을 관리하는 운영체제 핵심부임
- 쉘은 사용자의 명령을 해석해 프로그램 실행으로 연결하는 인터페이스임
- 파일시스템은 데이터를 파일과 디렉터리 구조로 조직하는 저장 계층임

## Ⅰ. 개요

- **정의/개념**: UNIX 시스템은 자원 관리와 보호를 담당하는 커널, 사용자 명령 해석과 실행을 담당하는 쉘, 데이터를 계층적으로 저장하고 접근하게 하는 파일시스템의 3요소로 구성되는 운영체제 구조임
- **배경/필요성**: 사용자 인터페이스와 핵심 자원 제어와 저장 구조를 분리해야 이식성과 안정성과 유연한 도구 조합이 가능하므로, UNIX는 이 세 요소를 명확히 구분해 발전해 왔음

## Ⅱ. 특징

- 커널과 사용자 공간을 분리해 안정성과 보호를 확보함
- 쉘은 명령·파이프·리다이렉션·스크립트로 프로그램 실행과 데이터 전달을 조합함
- 파일시스템은 모든 자원을 파일 인터페이스로 다루는 UNIX 철학과 맞물림
- 세 요소가 느슨하게 분리되어 유지보수와 확장이 용이함

## Ⅲ. 종류 및 비교

| 판단 기준 | 커널 | 쉘 | 파일시스템 |
|:---|:---|:---|:---|
| 역할 | 자원 관리와 시스템 호출 | 명령 해석과 스크립트 실행 | 데이터 저장과 메타데이터 관리 |
| 동작 계층 | 커널 공간 | 사용자 공간 | 커널 내부 핵심 계층 |
| 사용자 접점 | 직접 노출 적음 | 가장 직접적 | 파일과 디렉터리로 노출 |
| 제공 기능 | 자원 보호·스케줄링·시스템 호출 | 명령 해석·파이프·스크립트 | 파일·디렉터리·권한·메타데이터 관리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Kernel Core | 프로세스와 메모리와 장치와 시스템 호출을 관리해 UNIX 전체 동작의 기반을 이룸 |
| Shell Interface | 명령 파싱과 환경 변수와 파이프라인을 제공해 사용자의 작업을 프로그램 실행으로 변환함 |
| File System Layer | 파일과 디렉터리와 권한을 관리해 저장장치와 사용자 작업을 연결함 |
| System Call Boundary | 쉘과 응용이 커널 기능을 요청하는 공식 경계로 보안과 기능 확장의 기준점이 됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령 입력      | --> | 쉘 해석        | --> | 시스템 호출    | --> | 파일/프로세스 처리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령 입력**: 사용자가 쉘에 명령이나 스크립트를 입력함
2. **쉘 해석**: 쉘이 명령을 파싱하고 프로그램과 파이프와 리다이렉션을 구성함
3. **시스템 호출**: 필요한 파일 접근과 프로세스 생성과 장치 사용을 커널에 요청함
4. **파일 및 프로세스 처리**: 커널과 파일시스템이 실제 자원 작업을 수행하고 결과를 반환함

## Ⅵ. 실무 적용 및 유의점

1. 서버 운영 자동화에서는 쉘과 시스템 호출 경계를 이해한 뒤 스크립트를 표준화하되 복잡한 스크립트가 오류 처리 한계를 드러내지 않도록 공통 함수와 lint를 적용하고 script failure rate와 deployment success rate로 확인함
2. 다중 사용자 UNIX 환경에서는 파일시스템 권한과 디렉터리 체계를 함께 설계하되 커널 권한 모델과 어긋나면 접근 사고가 반복되므로 표준 권한 정책을 운영하고 permission drift count와 access incident rate로 확인함

## Ⅶ. 결론

UNIX는 커널의 자원 제어, 쉘의 명령 해석, 파일시스템의 영속 저장을 분리하고 시스템 호출과 파일 인터페이스로 연결함.
