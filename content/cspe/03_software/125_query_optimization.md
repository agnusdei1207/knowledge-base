## Ⅰ. 개요
- **정의**: SQL 실행 계획 중 최소 비용 계획을 선택하여 쿼리 응답 시간을 단축하는 기법
- **배경/필요성**: 동일 결과를 반환하는 실행 경로가 다수 존재하며, 경로 선택에 따라 수행 시간이 수십~수백 배 차이남
- **비유**: 같은 목적지를 가는 여러 경로 중 내비게이션이 교통 상황을 고려해 최단 경로를 추천하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 옵티마이저 동작 원리 | CBO vs RBO, 통계 정보 역할 | 논리 최적화와 물리 최적화 구분 필요 |

> 요약: 다수의 실행 경로에서 비용 기반으로 최적 계획을 선택하는 기법임

## Ⅱ. 구성요소
```text
SQL --> Parser --> Logical Plan --> Optimizer --> Physical Plan --> Executor
                                      |
                              Statistics + Cost Model
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Logical Plan | 관계 대수 기반 논리적 연산 트리 | 추상 경로 지도 |
| Statistics | 테이블 행 수, 컬럼 분포, 히스토그램 등 메타 정보 | 도로 교통량 데이터 |
| Cost Model | I/O·CPU·네트워크 비용을 수치화하는 추정 모델 | 내비게이션 소요 시간 계산 |
| Physical Plan | 구체적 접근 방법(Index Scan, Hash Join 등)이 확정된 실행 계획 | 실제 주행 경로 |

> 요약: 통계 정보와 비용 모델을 기반으로 논리 계획을 물리 계획으로 변환함

## Ⅲ. 절차
```text
SQL Parsing --> 논리 최적화 --> 비용 산정 --> 물리 계획 선택
```
- 1단계: SQL을 파싱하여 관계 대수 기반 논리 트리를 생성함
- 2단계: 조건 Push-Down, 불필요 컬럼 제거 등 논리 최적화 규칙을 적용함
- 3단계: 후보 물리 계획별 Cost Model로 예상 비용(I/O, CPU)을 산정함
- 4단계: 최소 비용 물리 계획을 선택하여 Executor에 전달함

> 요약: 파싱-논리 최적화-비용 산정-계획 선택 순서로 최적 실행 경로를 결정함

## Ⅳ. 문제점
- 통계 정보 부정확: 테이블 변경 후 통계 갱신 누락 시 비용 오추정으로 비효율 계획 선택
- 결합 순서 폭발: 다수 테이블 조인 시 후보 계획 수가 기하급수 증가하여 최적화 시간 과다
- 힌트 남용: 수동 힌트 과다 사용 시 데이터 변화에 적응하지 못하는 고정 계획 유지

> 요약: 통계 부정확, 조인 순서 폭발, 힌트 고정화가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 통계 자동 갱신 주기 설정 및 히스토그램 수집 활성화
2. 중기: 그리디·동적 프로그래밍 하이브리드로 조인 열거 범위 제한
3. 장기: Adaptive Query Optimization 도입으로 실행 중 계획 재조정 지원

> 요약: 통계 자동화, 열거 범위 제한, 적응형 최적화로 정확도와 효율을 개선함

## Ⅵ. 전망
- 발전 방향: ML 기반 학습형 옵티마이저(Learned Optimizer)로 비용 모델 정확도 향상 추세
- 기술사적 판단: 인덱스(122 참조)와 함께 DB 성능의 양대 축으로 지속 중요함
- 기술사 제언: Explain Plan 분석 역량과 통계 관리 체계를 병행 확보할 필요
