## Ⅰ. 개요
- **정의**: OLTP는 트랜잭션 처리 최적화 시스템, OLAP는 분석 질의 최적화 시스템
- **배경/필요성**: 트랜잭션 처리와 분석 워크로드는 I/O 패턴이 상이하므로 목적별 최적화 아키텍처가 필요함
- **비유**: OLTP는 은행 창구(건별 입출금), OLAP는 경영 보고서(대량 집계)와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 워크로드 특성 비교 능력 | 행 기반 vs 열 기반 저장, 정규화 vs 비정규화 | 단순 정의 나열이 아닌 설계 차이 근거 서술 |

> 요약: 트랜잭션과 분석이라는 상이한 워크로드에 최적화된 두 가지 처리 패러다임임

## Ⅱ. 구성요소
```text
        OLTP                          OLAP
[사용자 트랜잭션]              [분석 쿼리/리포트]
        |                              |
   [행 기반 DB]                  [열 기반 DW]
        |                              |
   [정규화 스키마]             [스타/스노우플레이크 스키마]
        |                              |
   [인덱스 최적화]             [집계/파티셔닝 최적화]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| OLTP 저장소 | 행 기반 저장으로 단건 읽기/쓰기에 최적화된 DB | 서류 캐비닛 |
| OLAP 저장소 | 열 기반 저장으로 대량 집계에 최적화된 DW | 통계 대장 |
| 정규화 스키마 | 중복 제거 목적의 3NF 이상 정규화 구조 | 원본 서류 분류함 |
| 스타 스키마 | 팩트-디멘전 구조로 조인 단순화한 비정규화 모델 | 보고서 양식 |

> 요약: OLTP는 행 기반·정규화, OLAP는 열 기반·비정규화로 워크로드에 맞게 분리된 구조임

## Ⅲ. 절차
```text
[OLTP 운영] --> [ETL/CDC 추출] --> [OLAP 적재] --> [분석/리포팅]
```
- 1단계: OLTP 운영 — 업무 트랜잭션이 행 기반 DB에 실시간 기록됨
- 2단계: ETL/CDC 추출 — 운영 데이터를 분석용으로 추출·변환함
- 3단계: OLAP 적재 — 변환된 데이터를 스타 스키마 기반 DW에 적재함
- 4단계: 분석/리포팅 — 대량 집계 쿼리로 비즈니스 인사이트를 도출함

> 요약: OLTP에서 발생한 데이터를 ETL로 OLAP에 적재하여 분석하는 흐름임

## Ⅳ. 문제점
- 데이터 지연: ETL 배치 주기로 인해 분석 시점과 운영 시점 간 시차 발생
- 이중 관리 비용: OLTP·OLAP 별도 운영으로 인프라·운영 비용 증가
- 스키마 변경 연쇄: OLTP 스키마 변경 시 ETL·OLAP 스키마 동시 수정 필요

> 요약: 데이터 지연, 이중 비용, 스키마 연쇄 변경이 주요 문제임

## Ⅴ. 개선방안
1. 단기: CDC(156 참조) 기반 실시간 추출로 분석 데이터 지연 최소화
2. 중기: HTAP(하이브리드) DB 도입으로 단일 시스템에서 트랜잭션·분석 동시 처리
3. 장기: 스키마 레지스트리 기반 변경 전파 자동화로 연쇄 수정 비용 절감

> 요약: 실시간 추출, HTAP 통합, 스키마 자동화로 단계적 개선이 필요함

## Ⅵ. 전망
- 발전 방향: HTAP DB의 성숙으로 OLTP·OLAP 경계 점진적 융합
- 기술사적 판단: 실시간 분석 수요 증가로 배치 ETL 중심 아키텍처의 비중 감소 전망
- 기술사 제언: 워크로드 특성을 분석하여 분리형·통합형 아키텍처를 선택적으로 적용할 필요
