## Ⅰ. 개요
- 정의: 프로세스가 생성된 뒤 준비, 실행, 대기, 종료 상태를 거치는 상태 전이 과정
- 배경: CPU, I/O, 메모리 점유 상태가 달라지므로 스케줄러가 상태별로 실행 대상을 관리해야 함
- 출제 의도: 스케줄링에 따른 상태 전이(Transition)와 보류 상태의 필요성 파악

## Ⅱ. 구성요소
```
    Admit       Dispatch      Timeout
New ----> Ready --------> Running ----> Exit
           ^   \           / |
           |    \   Wait  /  | Terminate
           |     v       v   |
           +----- Blocked ---+
```
| 구성요소 | 설명 | 스케줄링 의미 |
| :--- | :--- | :--- |
| Ready | CPU 할당을 기다리는 대기 큐 상태 | 디스패치 후보 |
| Running | CPU를 할당받아 명령어를 실행 중인 상태 | 현재 CPU 점유 |
| Blocked | I/O 등 이벤트 발생을 기다리며 일시 중단된 상태 | CPU 할당 제외 |
> 요약: 프로세스는 CPU 할당 여부와 이벤트 대기 여부에 따라 준비·실행·대기 상태로 전이함.

## Ⅲ. 절차
```
[New] -> [Ready] <-> [Running] -> [Waiting] -> [Ready] -> [Terminated]
```
1. 프로세스 생성(New) 후 메모리 할당 및 PCB 등록을 통해 준비 상태로 전이
2. 스케줄러의 디스패치(Dispatch)에 의해 실행 상태로 전환되어 연산 수행
3. I/O 요청 시 대기(Waiting) 상태로, 할당 시간 만료 시 준비 상태로 회귀
4. 모든 작업 완료 후 자원 반납 및 PCB 제거를 통해 종료(Terminated) 처리
> 요약: 스케줄러는 프로세스의 CPU 할당·I/O 대기·작업 완료에 따라 상태와 큐를 변경함.

## Ⅳ. 문제점
- 원인: 메모리 부족 시 활성 상태의 프로세스를 유지하지 못해 시스템 지연 발생함
- 원인: 특정 프로세스가 실행 상태를 독점하여 타 프로세스의 기아(Starvation) 초래함

## Ⅴ. 개선방안
- (단기) 스왑 아웃(Swap-out)을 통한 지연/보류(Suspended) 상태 도입으로 메모리 확보
- (중기) 우선순위 기반 스케줄링 및 에이징 기법 적용으로 실행 기회 균등 배분
- (장기) 가상 메모리와 스케줄링 지표를 함께 반영해 보류·복귀 기준 정교화

## Ⅵ. 전망
- 서버 OS는 대기 원인과 실행 이력을 이용해 디스패치 지연을 줄이는 방향으로 발전함
- 엣지 환경에서는 전력 절감을 위해 상태 보존과 빠른 복귀 시간이 설계 기준이 됨

## 작성 근거(검토용)

- 생명주기는 단순 과정 설명보다 CPU, I/O, 메모리 점유 상태가 스케줄링 결정을 바꾸는 흐름으로 설명해야 함
- AI 기반 전망 단정과 추상 전망을 제거하고 디스패치 지연, 상태 보존, 복귀 시간처럼 측정 가능한 판단어로 바꿈
