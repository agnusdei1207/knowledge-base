## 미리 알고가기

- 준비 상태: CPU 할당을 기다리는 실행 가능 상태임
- 실행 상태: CPU를 할당받아 명령어를 처리하는 상태임
- 대기 상태: I/O 완료나 이벤트 발생 전까지 CPU 할당 대상에서 제외된 상태임

## 작성 근거(검토용)

- 프로세스 상태는 CPU 할당·이벤트 대기·작업 완료라는 전이 원인으로 구분함
- 상태와 큐의 관계를 정적 구조로, 디스패치·선점·대기·종료를 실제 전이로 분리함
- 운영체제 사례는 준비 큐 대기와 I/O 대기 상태를 직접 측정하도록 구성함

## Ⅰ. 개요
- **정의/개념**: 프로세스 생명주기는 생성된 프로세스가 준비·실행·대기·종료 상태를 오가며 CPU와 I/O 자원을 사용하는 상태 전이 모델임
- **배경/필요성**: 실행 가능 작업과 이벤트 대기 작업을 구분해 CPU를 배분하기 위해 프로세스 상태와 전이 기준이 필요함

## Ⅱ. 특징

- 프로세스 상태는 CPU 할당 여부와 이벤트 대기 여부를 나타냄
- 준비 큐는 실행 가능한 프로세스를, 대기 큐는 이벤트별 대상을 관리함
- 디스패치·선점·I/O 요청·이벤트 완료가 준비·실행·대기 전이를 발생시킴
- 종료 상태에서는 PCB와 메모리·파일 자원을 회수함

## Ⅲ. 종류 및 비교

| 상태 | 의미 | 진입 조건 | 다음 전이 |
|:---|:---|:---|:---|
| 생성 | PCB와 주소 공간을 구성 중임 | 프로세스 생성 요청 | 승인 후 준비 |
| 준비 | CPU 할당을 기다림 | 생성 승인·선점·이벤트 완료 | 디스패치 후 실행 |
| 실행 | CPU에서 명령을 처리함 | 스케줄러 디스패치 | 선점·대기·종료 |
| 대기 | I/O나 이벤트 완료를 기다림 | 실행 중 I/O·동기화 요청 | 이벤트 완료 후 준비 |
| 종료 | 실행을 마치고 자원을 회수함 | 정상 완료·강제 종료 | PCB 제거 |

> 요약: CPU 할당은 준비를 실행으로, 선점은 실행을 준비로, I/O 요청은 실행을 대기로 전이시킴.

## Ⅳ. 구성요소 및 구조
```
    Admit       Dispatch      Timeout
New ----> Ready --------> Running ----> Exit
           ^   \           / |
           |    \   Wait  /  | Terminate
           |     v       v   |
           +----- Blocked ---+
```
| 구성요소 | 설명 | 스케줄링 의미 |
| :--- | :--- | :--- |
| 준비 큐 | CPU 할당을 기다리는 실행 가능 프로세스를 보관함 | 디스패치 후보 |
| 대기 큐 | I/O·동기화 이벤트별 대기 프로세스를 보관함 | 이벤트 완료 대상 |
| PCB | 현재 상태와 CPU 문맥·자원 정보를 저장함 | 상태 복원 |
> 요약: 프로세스는 CPU 할당 여부와 이벤트 대기 여부에 따라 준비·실행·대기 상태로 전이함.

## Ⅴ. 원리 및 절차 흐름도
```
[New] -> [Ready] <-> [Running] -> [Waiting] -> [Ready] -> [Terminated]
```
1. **생성·준비**: PCB와 주소 공간을 구성하고 준비 큐에 등록함
2. **디스패치**: 스케줄러가 준비 프로세스를 선택해 실행 상태로 전환함
3. **선점·대기**: 시간 할당량이 끝나면 준비로, I/O를 요청하면 대기로 전환함
4. **완료·종료**: 실행을 마치면 자원을 반납하고 PCB를 제거함
> 요약: 스케줄러는 프로세스의 CPU 할당·I/O 대기·작업 완료에 따라 상태와 큐를 변경함.

## Ⅵ. 실무 사례

1. API 서버 운영체제는 준비 큐 길이와 디스패치 지연을 측정해 시간 할당량을 조정함
2. I/O 집약 프로세스는 대기 큐를 이벤트별로 분리하고 I/O 대기시간과 CPU 유휴율을 확인함

## Ⅶ. 결론

- 프로세스 상태 전이는 CPU 할당·선점·이벤트 대기·완료 조건에 따라 큐와 자원 상태를 변경함
