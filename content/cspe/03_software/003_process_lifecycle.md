## Ⅰ. 개요
- 정의: 프로세스가 생성되어 종료될까지 거치는 일련의 상태 변화 과정
- 배경: 한정된 CPU 자원을 다수 프로세스가 공유하기 위해 상태 관리가 필수적임
- 출제 의도: 스케줄링에 따른 상태 전이(Transition)와 보류 상태의 필요성 파악

## Ⅱ. 구성요소
```
    Admit       Dispatch      Timeout
New ----> Ready --------> Running ----> Exit
           ^   \           / |
           |    \   Wait  /  | Terminate
           |     v       v   |
           +----- Blocked ---+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Ready | CPU 할당을 기다리는 대기 큐 상태 | 줄 서서 기다림 |
| Running | CPU를 할당받아 명령어를 실행 중인 상태 | 서비스 이용 중 |
| Blocked | I/O 등 이벤트 발생을 기다리며 일시 중단된 상태 | 재료 기다림 |
> 요약: 프로세스는 준비, 실행, 대기 상태를 반복하며 생명주기를 유지함.

## Ⅲ. 절차
```
[New] -> [Ready] <-> [Running] -> [Waiting] -> [Ready] -> [Terminated]
```
1. 프로세스 생성(New) 후 메모리 할당 및 PCB 등록을 통해 준비 상태로 전이
2. 스케줄러의 디스패치(Dispatch)에 의해 실행 상태로 전환되어 연산 수행
3. I/O 요청 시 대기(Waiting) 상태로, 할당 시간 만료 시 준비 상태로 회귀
4. 모든 작업 완료 후 자원 반납 및 PCB 제거를 통해 종료(Terminated) 처리
> 요약: 상태 전이도를 통해 프로세스의 자원 점유 상태를 동적으로 관리함.

## Ⅳ. 문제점
- 원인: 메모리 부족 시 활성 상태의 프로세스를 유지하지 못해 시스템 지연 발생함
- 원인: 특정 프로세스가 실행 상태를 독점하여 타 프로세스의 기아(Starvation) 초래함

## Ⅴ. 개선방안
- (단기) 스왑 아웃(Swap-out)을 통한 지연/보류(Suspended) 상태 도입으로 메모리 확보
- (중기) 우선순위 기반 스케줄링 및 에이징 기법 적용으로 실행 기회 균등 배분
- (장기) 가상 메모리 관리 최적화 및 적응형 스케줄링 알고리즘 고도화

## Ⅵ. 전망
- 지능형 OS에서는 프로세스 동작 패턴을 학습하여 상태 전이 시점을 예측하는 최적화 도입 예상
- 엣지 컴퓨팅 환경에서의 저전력 관리를 위해 초경량 상태 보존 및 고속 복구 기술이 핵심이 될 것임
