## Ⅰ. 개요
- **정의**: 프로세스가 생성부터 종료까지 거치는 상태 전이의 전체 흐름임
- **배경/필요성**: OS가 CPU·메모리를 공정하게 배분하려면 각 프로세스의 현재 상태를 추적·관리할 구조가 필요함
- **비유**: 음식점 주문이 접수-조리대기-조리중-서빙-퇴장으로 흐르는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 5-상태 모델의 전이 조건 이해 | 각 전이를 유발하는 이벤트(인터럽트, I/O 등) | Suspended 상태를 포함한 7-상태 확장 모델도 언급할 것 |

> 요약: 프로세스 상태 전이를 정확히 이해해야 스케줄링·자원 관리 설계가 가능함

## Ⅱ. 구성요소
```text
          admit        dispatch
New -------> Ready -------> Running
               ^               |
               |  timeout      | exit
               +-----------+   +------> Terminated
                            |
               I/O complete |  I/O wait
               +------------+-------> Waiting
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| New | 프로세스가 생성되어 PCB가 할당된 초기 상태임 | 입학 원서 접수 |
| Ready | CPU 할당을 대기하는 상태이며 Ready Queue에 위치함 | 대기실에서 호명 대기 |
| Running | CPU를 점유하여 명령어를 실행 중인 상태임 | 진료 중 |
| Waiting | I/O 또는 이벤트 완료를 대기하는 상태임 | 검사 결과 대기 |
| Terminated | 실행 완료 후 자원 회수를 기다리는 상태임 | 퇴원 수속 |

> 요약: 5-상태 모델은 New-Ready-Running-Waiting-Terminated로 구성됨

## Ⅲ. 절차
```text
New --[admit]--> Ready --[dispatch]--> Running --[exit]--> Terminated
                  ^                      |
                  |---[timeout]----------+
                  |                      |
                  +--[I/O done]-- Waiting <--[I/O wait]--+
```
- 1단계: `fork()`로 프로세스를 생성하고 New 상태에서 PCB를 초기화함
- 2단계: 장기 스케줄러가 승인하면 Ready Queue에 진입함
- 3단계: 단기 스케줄러가 dispatch하여 Running 상태로 전환하고 CPU를 할당함
- 4단계: I/O 요청 시 Waiting, 타임아웃 시 Ready로 전이하며, 완료 시 Terminated로 전환함

> 요약: admit-dispatch-exit 흐름에 timeout·I/O 전이가 결합된 순환 구조임

## Ⅳ. 문제점
- 좀비 프로세스: 부모가 `wait()`를 호출하지 않으면 Terminated 상태의 PCB가 회수되지 않음 — PID 자원 고갈됨
- Ready Queue 과적: 프로세스가 과도하게 생성되면 Ready Queue가 비대해짐 — 응답 시간이 지연됨
- 기아 현상: 낮은 우선순위 프로세스가 Ready에서 Running으로 전이되지 못함 — 무한 대기 발생함

> 요약: 자원 미회수, 큐 과적, 기아가 생명주기 관리의 주요 문제임

## Ⅴ. 개선방안
1. 단기: 부모 프로세스에 SIGCHLD 핸들러를 등록하여 좀비를 즉시 회수함
2. 중기: 승인 제어(Admission Control)로 동시 프로세스 수를 제한하여 큐 과적을 방지함
3. 장기: 에이징(Aging) 기법으로 대기 시간에 비례해 우선순위를 상향하여 기아를 해소함

> 요약: 시그널 처리, 승인 제어, 에이징으로 생명주기 문제를 해결함

## Ⅵ. 전망
- 발전 방향: cgroup 기반 프로세스 그룹 관리로 컨테이너 단위 생명주기 제어가 확산됨
- 기술사적 판단: 클라우드 환경에서 프로세스 생성·종료 빈도가 높아져 경량화·자동 회수의 중요성이 증대됨
- 기술사 제언: 모니터링 체계와 자동 회수 정책을 결합한 생명주기 거버넌스 수립이 필요
