## Ⅰ. 개요
- 고객의 요구사항 변화에 유연하게 대응하기 위해 개발자 중심의 실천 방안을 강조함.
- "의사소통, 단순성, 피드백, 용기, 존중"의 5가지 핵심 가치를 지향함.
- 출제 의도: 고품질 코드 생산을 위한 XP 실천 기법(Practices)의 이해도 평가.

## Ⅱ. 구성요소
- XP 주요 실천 기법
[TDD] + [Pair Programming] + [Continuous Integration]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Pair Programming | 두 명의 개발자가 하나의 컴퓨터에서 협업함 | 운전사와 내비게이터 |
| Test Driven Dev | 테스트 코드를 먼저 작성한 후 개발 수행함 | 설계도 검토 후 시공 |
| Refactoring | 기능을 유지하며 코드 내부 구조를 개선함 | 인테리어 보수 |
> 요약: 실천적 기법들을 통해 개발 프로세스의 군더더기를 제거함.

## Ⅲ. 절차
- XP 개발 프로세스
[User Stories] -> [Release Planning] -> [Spikes] -> [Iteration] -> [Acceptance]

1. 사용자 스토리: 고객이 필요한 기능을 간단한 카드로 작성함.
2. 반복 계획: 짧은 주기(1~3주) 동안 개발할 스토리를 선정함.
3. 소규모 릴리즈: 기능을 빠르게 완성하여 고객에게 빈번히 전달함.
4. 인수 테스트: 고객이 직접 테스트를 수행하여 승인 여부 결정함.
> 요약: 잦은 릴리즈와 피드백을 통해 고객 만족도를 극대화함.

## Ⅳ. 문제점
- 개발자의 높은 역량 요구 및 페어 프로그래밍에 따른 인건비 부담 증가.

## Ⅴ. 개선방안
- 부분적 XP 기법 도입 및 코드 리뷰 시스템 강화를 통한 품질 확보.

## Ⅵ. 전망
- AI 페어 프로그래머(Copilot 등)가 인간의 페어 역할을 일부 대체하는 추세.
- TDD를 넘어선 테스트 자동화 프레임워크와 CI/CD 파이프라인의 완전 결합.
