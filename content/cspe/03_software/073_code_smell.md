## 미리 알고가기

- 코드 스멜은 현재 기능 오류는 없지만 유지보수 위험을 나타내는 구조 신호임
- 긴 메서드와 중복 코드와 큰 클래스가 대표 예시임
- 변경 빈도·결함 이력·결합 범위가 높은 코드 스멜부터 리팩터링 우선순위를 높임

## 작성 근거(검토용)

- 코드 스멜은 성격, 발견 방식, 대응 방식, 영향 시점을 핵심 비교축으로 선정함
- 구성은 구조·의존성·가독성 징후와 변경 집중 영역을 중심으로 제시함
- 실무 판단은 모듈별 스멜 수, 기능 반영시간, 스멜 재발률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 코드 스멜은 현재 오동작은 아니지만 가독성·변경 용이성·테스트 가능성을 낮춰 미래 유지보수 위험을 알리는 구조 징후임
- **배경/필요성**: 중복·복잡도·결합이 누적되기 전에 구조 악화 신호를 찾아 개선 우선순위를 정할 기준이 필요함

## Ⅱ. 특징

- 코드 스멜은 현재 기능 오류가 아닌 구조 악화 신호임
- 같은 변경 경로에 여러 스멜이 존재하면 수정 범위와 이해 비용이 늘어남
- 정적 분석과 코드 리뷰로 운영 전 구조 징후를 발견함
- 변경 빈도·결함 이력·결합 범위에 따라 스멜 개선 우선순위를 정함

## Ⅲ. 종류 및 비교

| 판단 기준 | 코드 스멜 | 실제 버그 |
|:---|:---|:---|
| 성격 | 미래 유지보수 위험을 알려 주는 구조 신호임 | 현재 기능 오동작을 만드는 결함임 |
| 발견 방식 | 리뷰·정적 분석에서 중복·복잡도·책임 집중 확인 | 테스트 실패·운영 장애에서 실제 기능 오류 확인 |
| 대응 방식 | 변경 위험을 평가해 리팩터링하고 외부 동작 유지 | 결함 원인을 수정하고 회귀 테스트 수행 |
| 주된 영향 | 이후 변경 비용과 이해 비용을 높임 | 현재 기능 실패와 사용자 피해를 만듦 |

> 요약: 코드 스멜은 미래 유지보수 위험을 알리는 구조 신호이고 버그는 현재 기능 오동작을 만드는 결함임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 구조 스멜 | 긴 메서드와 큰 클래스와 중복 코드처럼 구조 비대화를 드러냄 |
| 의존성 스멜 | 순환 의존과 과도한 결합처럼 변경 파급을 키우는 징후를 보여줌 |
| 이름과 가독성 스멜 | 의미가 불명확한 이름과 숨은 의도가 코드 이해 비용을 높임 |
| 변경 집중 영역 | 변경 빈도와 결함 이력이 높은 영역의 스멜을 우선 개선함 |

> 요약: 구조·의존성·가독성 스멜이 변경 집중 영역에 있을수록 리팩터링 우선순위를 높임.

## Ⅵ. 실무 사례

1. 레거시 서비스는 변경 빈도가 높은 모듈부터 개선하고 모듈별 스멜 수·기능 반영시간을 확인함
2. 개발팀은 코드 리뷰 스멜 기준을 통일하고 판단 일치율·스멜 재발률을 확인함

## Ⅶ. 결론

코드 스멜은 미래 유지보수 위험을 나타내므로 변경 빈도와 결합 범위에 따라 개선 우선순위를 정함
