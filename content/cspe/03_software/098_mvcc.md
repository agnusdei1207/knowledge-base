## 미리 알고가기

- MVCC는 같은 행의 여러 버전을 유지해 읽기와 쓰기가 서로 덜 기다리게 만드는 동시성 제어 방식임
- 스냅샷 읽기는 트랜잭션이 시작한 시점에 보이던 버전만 읽는 방식임
- 오래된 버전을 정리하는 작업이 늦어지면 저장 공간과 조회 비용이 함께 커질 수 있음

## Ⅰ. 개요

- **정의/개념**: MVCC는 데이터를 갱신할 때 기존 값을 바로 덮어쓰지 않고 새 버전을 추가로 기록해 읽기 트랜잭션은 자신이 볼 수 있는 시점의 버전을 읽고 쓰기 충돌은 별도로 판정하는 동시성 제어 방식임.
- **배경/필요성**: 주문 조회와 목록 조회처럼 읽기 요청이 많은 시스템에서 모든 접근을 잠금으로만 제어하면 대기가 길어지므로, 읽기 일관성을 유지하면서도 동시 처리량을 높일 방식이 필요함.

## Ⅱ. 특징

- 읽기 트랜잭션이 쓰기 잠금을 오래 기다리지 않아 조회 지연을 줄일 수 있음
- 스냅샷 기반으로 같은 트랜잭션 안에서 일관된 읽기 결과를 제공함
- 새 버전을 계속 쌓으므로 정리 주기와 장기 트랜잭션 관리가 필수임
- 읽기는 편해지지만 쓰기 충돌과 직렬화 실패가 사라지는 것은 아님

## Ⅲ. 종류 및 비교

| 판단 기준 | 락 중심 제어 | MVCC |
|:---|:---|:---|
| 읽기 처리 방식 | 잠금 상태를 직접 확인하며 대기할 수 있음 | 보이는 버전을 골라 읽으므로 대기가 적음 |
| 강점 | 충돌 규칙이 단순하고 제어가 명확함 | 조회 성능이 좋고 스냅샷 일관성을 제공함 |
| 주요 부담 | 잠금 경합이 커지기 쉬움 | 버전 누적과 정리 비용을 관리해야 함 |
| 적합 환경 | 쓰기 충돌 통제가 우선인 업무 | 읽기 비중이 높은 온라인 트랜잭션 처리와 혼합 조회 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 버전 정보 | 각 행의 생성 시점과 삭제 시점 또는 트랜잭션 식별자를 기록해 어느 버전이 보이는지 판단함 |
| 스냅샷 뷰 | 트랜잭션 시작 시점 기준으로 읽을 수 있는 버전 범위를 정함 |
| 쓰기 충돌 규칙 | 같은 행을 동시에 바꿀 때 어느 트랜잭션을 성공시키고 재시도할지 정함 |
| 정리 작업 | 더 이상 보이지 않는 오래된 버전을 회수해 저장 공간과 탐색 비용을 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 트랜잭션 시작   | --> | 스냅샷 기준 읽기 | --> | 새 버전 기록    | --> | 구버전 정리     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **트랜잭션 시작**: 트랜잭션이 자신이 볼 수 있는 시점 범위를 잡음
2. **스냅샷 기준 읽기**: 현재 시점에 보이는 버전을 골라 읽음
3. **새 버전 기록**: 갱신이 발생하면 새 버전을 만들고 충돌을 검사함
4. **구버전 정리**: 더 이상 참조되지 않는 버전을 정리함

## Ⅵ. 실무 적용 및 유의점

1. 읽기 비중이 높은 주문 조회와 사용자 화면에서는 MVCC로 조회 대기를 줄이되 장기 트랜잭션이 버전 정리를 막지 않게 제한 시간을 두고 오래된 스냅샷 유지 시간과 버전 팽창률로 확인함.
2. 동시 수정이 많은 업무에서는 MVCC를 쓰더라도 쓰기 충돌이 남으므로 재시도 정책과 정리 주기를 함께 설계하고 직렬화 실패율과 정리 지연 시간으로 확인함.

## Ⅶ. 결론

MVCC는 읽기 성능을 높이는 기능이면서 동시에 버전 정리와 충돌 재시도를 함께 관리해야 효과가 유지되는 동시성 구조임.
