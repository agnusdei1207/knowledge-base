## 미리 알고가기

- MVCC는 같은 데이터에 대해 여러 버전을 유지해 읽기와 쓰기 충돌을 줄이는 방식임
- 주로 스냅샷 읽기와 버전 체인을 이용해 일관된 조회를 제공함
- 버전 정리와 장기 트랜잭션 관리가 성능의 핵심임

## Ⅰ. 개요

- **정의/개념**: MVCC는 데이터 변경 시 기존 값을 덮어쓰지 않고 버전을 추가로 유지해 읽기 트랜잭션은 자신이 보아야 할 스냅샷 버전을 조회하고 쓰기 트랜잭션은 충돌 여부를 별도로 판정하는 동시성 제어 방식임
- **배경/필요성**: 읽기 비중이 높은 서비스에서 락 중심 제어만 사용하면 조회 대기와 경합이 크게 늘어나므로, 읽기 일관성과 동시 처리량을 함께 확보할 방식이 필요함

## Ⅱ. 특징

- 읽기와 쓰기 충돌을 완화해 조회 지연을 줄임
- 스냅샷 일관성을 제공해 반복 읽기 안정성을 높일 수 있음
- 버전 누적이 커지면 저장 공간과 vacuum 비용이 증가함
- 장기 트랜잭션은 오래된 버전 정리를 막아 전체 성능을 악화시킬 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 락 중심 제어 | MVCC |
|:---|:---|:---|
| 읽기 대기 | 발생 가능 | 대체로 낮음 |
| 강점 | 구현 단순성과 명시적 통제 | 조회 성능과 스냅샷 일관성 |
| 한계 | 경합 증가 | 버전 관리 비용 |
| 적합 환경 | 쓰기 충돌 관리 중심 | 읽기 비중 높은 OLTP |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Version Chain | 각 레코드의 변경 이력을 연결해 시점별 조회를 가능하게 함 |
| Snapshot View | 트랜잭션 시작 시점 기준으로 보아야 할 가시 버전을 결정함 |
| Write Conflict Rule | 동일 데이터 갱신 충돌을 감지해 커밋 성공 여부를 판정함 |
| Vacuum or Cleanup | 불필요해진 오래된 버전을 정리해 저장 공간과 탐색 비용을 통제함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스냅샷 생성    | --> | 버전 읽기      | --> | 새 버전 기록    | --> | 구버전 정리     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스냅샷 생성**: 트랜잭션이 볼 수 있는 시점 범위를 정함
2. **버전 읽기**: 가시성 규칙에 맞는 버전을 조회함
3. **새 버전 기록**: 갱신 시 새 버전을 추가하고 충돌을 검사함
4. **구버전 정리**: 더 이상 필요 없는 버전을 회수함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 장기 트랜잭션이 오래된 스냅샷을 붙잡고 있으면 버전 정리가 지연되어 저장 공간과 조회 비용이 함께 증가할 수 있음
   - 해결방안: long-running transaction timeout과 cleanup policy를 운영하고 version bloat ratio와 oldest snapshot age로 검증함
2. 문제: 버전 기반 읽기 일관성을 과신하면 쓰기 충돌과 갱신 손실 관리가 느슨해질 수 있음
   - 해결방안: write conflict detection과 retry 전략을 강화하고 serialization failure rate와 retry success rate로 검증함
3. 문제: vacuum 주기와 부하 창이 맞지 않으면 평상시 성능보다 정리 작업이 더 큰 병목이 될 수 있음
   - 해결방안: cleanup scheduling을 workload에 맞추고 vacuum lag와 storage reclaim efficiency로 검증함

## Ⅶ. 적용 사례

- 온라인 주문 DB에서는 장기 트랜잭션 제한을 운영하고 확인 지표는 version bloat ratio와 oldest snapshot age임
- 동시 수정이 많은 업무 DB에서는 충돌 재시도 정책을 적용하고 확인 지표는 serialization failure rate와 retry success rate임
- 대규모 SaaS DB에서는 정리 작업 스케줄을 최적화하고 확인 지표는 vacuum lag와 storage reclaim efficiency임

## Ⅷ. 결론

MVCC의 실무 가치는 읽기 성능 향상 자체보다 스냅샷 일관성과 버전 정리 비용을 함께 통제해 동시성 품질을 안정화하는 데 있음.
