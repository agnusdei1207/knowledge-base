## 미리 알고가기

- MVCC는 같은 행의 여러 버전을 유지해 읽기와 쓰기가 서로 덜 기다리게 만드는 동시성 제어 방식임
- 스냅샷 읽기는 트랜잭션이 시작한 시점에 보이던 버전만 읽는 방식임
- 오래된 버전을 정리하는 작업이 늦어지면 저장 공간과 조회 비용이 함께 커질 수 있음

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- MVCC는 행 버전, 스냅샷 가시성, 쓰기 충돌, 구버전 정리를 핵심 축으로 설명함
- 비교표는 락 중심 제어와 MVCC의 읽기 대기·일관성 기준·관리 비용·적합 업무를 대비함
- 주문 조회와 동시 갱신 DB는 버전 팽창률·직렬화 실패율로 검증함

## Ⅰ. 개요

- **정의/개념**: MVCC는 갱신 시 새 행 버전을 만들고 트랜잭션 스냅샷에 보이는 버전을 선택해 읽는 동시성 제어 방식임
- **배경/필요성**: 읽기·쓰기가 병행되는 DB의 잠금 대기를 줄이면서 트랜잭션별 일관된 조회 결과를 제공하기 위해 다중 버전 관리가 필요함

## Ⅱ. 특징

- 읽기 트랜잭션이 쓰기 잠금을 오래 기다리지 않아 조회 지연을 줄일 수 있음
- 스냅샷 기반으로 같은 트랜잭션 안에서 일관된 읽기 결과를 제공함
- 새 버전이 누적되므로 정리 주기와 장기 트랜잭션 시간을 관리해야 함
- 읽기는 편해지지만 쓰기 충돌과 직렬화 실패가 사라지는 것은 아님

## Ⅲ. 종류 및 비교

| 판단 기준 | 락 중심 제어 | MVCC |
|:---|:---|:---|
| 읽기 처리 방식 | 잠금 상태를 직접 확인하며 대기할 수 있음 | 보이는 버전을 골라 읽으므로 대기가 적음 |
| 읽기 일관성 | 잠금 획득 시점의 현재 값 읽기 | 트랜잭션 스냅샷에 보이는 버전 읽기 |
| 주요 부담 | 잠금 경합이 커지기 쉬움 | 버전 누적과 정리 비용을 관리해야 함 |
| 대표 환경 | 쓰기 순서와 잠금 충돌을 직접 통제하는 업무 | 읽기와 쓰기를 병행하는 OLTP·혼합 조회 업무 |

> 요약: 락 중심 제어는 현재 값의 잠금을 기다리고 MVCC는 스냅샷에 보이는 행 버전을 읽음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 버전 정보 | 각 행의 생성 시점과 삭제 시점 또는 트랜잭션 식별자를 기록해 어느 버전이 보이는지 판단함 |
| 스냅샷 뷰 | 트랜잭션 시작 시점 기준으로 읽을 수 있는 버전 범위를 정함 |
| 쓰기 충돌 규칙 | 같은 행을 동시에 바꿀 때 어느 트랜잭션을 성공시키고 재시도할지 정함 |
| 정리 작업 | 더 이상 보이지 않는 오래된 버전을 회수해 저장 공간과 탐색 비용을 줄임 |

> 요약: 행 버전 정보와 스냅샷 뷰가 읽기 가시성을 정하고 충돌 규칙·정리 작업이 쓰기와 구버전을 처리함.

## Ⅴ. 원리 및 절차 흐름도

1. **트랜잭션 시작**: 트랜잭션이 자신이 볼 수 있는 시점 범위를 잡음
2. **스냅샷 기준 읽기**: 현재 시점에 보이는 버전을 골라 읽음
3. **새 버전 기록**: 갱신이 발생하면 새 버전을 만들고 충돌을 검사함
4. **구버전 정리**: 더 이상 참조되지 않는 버전을 정리함

> 요약: 스냅샷 시점의 버전을 읽고 갱신은 새 버전으로 기록한 뒤 참조가 끝난 구버전을 정리함.

## Ⅵ. 실무 사례

1. 주문 조회 DB는 장기 트랜잭션 제한 시간을 설정하고 최대 스냅샷 유지 시간·버전 팽창률을 확인함
2. 재고 갱신 DB는 쓰기 충돌 재시도와 버전 정리를 적용하고 직렬화 실패율·정리 지연을 확인함

## Ⅶ. 결론

- MVCC는 스냅샷 가시성·쓰기 충돌·구버전 정리를 함께 관리하는 다중 버전 동시성 구조임
