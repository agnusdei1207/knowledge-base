## Ⅰ. 개요
- 정의: SW의 품질, 크기, 복잡도 등을 정량적으로 측정하기 위한 소프트웨어 도구
- 배경: 코드 규모·복잡도·중복·커버리지 변화를 같은 기준으로 측정하고 비교할 필요
- 출제 의도: 주요 메트릭(LOC, Cyclomatic Complexity 등) 및 도구의 활용 역량 평가

## Ⅱ. 구성요소
- 구조도
  [Source Code] -> [Metric Tool] -> [Reports/Dashboard]
                             |-- Size (LOC)
                             |-- Complexity (McCabe)
                             |-- Quality (Duplicate)

- 구성요소 표
| 메트릭 종류 | 설명 | 도구 예시 |
| :--- | :--- | :--- |
| 복잡도 메트릭 | McCabe의 순환 복잡도 측정 | Understand, Lizard |
| 규모 메트릭 | 코드 라인 수(LOC), 기능 점수(FP) | CLOC, FP 계산기 |
| 품질 메트릭 | 결함 밀도, 코드 커버리지 | JaCoCo, Cobertura |
> 요약: 소스와 테스트 결과에서 규모·복잡도·중복·커버리지 지표를 산출하여 대시보드로 제공함

## Ⅲ. 절차
- 흐름도
  지표 선정 -> 데이터 수집 -> 정규화/분석 -> 시각화 및 피드백
- 4단계 설명
1. 지표 선정: 프로젝트 목표에 부합하는 핵심 측정 항목(KPI) 정의
2. 데이터 수집: 정적·동적 분석 도구를 연동하여 커밋이나 빌드 단위의 데이터 추출
3. 정규화/분석: 수집된 데이터를 기준치와 비교하여 품질 수준 진단
4. 시각화 및 피드백: 대시보드를 통해 현황 공유 및 취약 구간 리팩토링 유도
> 요약: 정량적 품질 지표의 지속적 모니터링을 통한 잠재적 리스크 조기 식별

## Ⅳ. 문제점
- 측정 수치(LOC 등)에만 매몰되어 실제 코드의 유연성이나 가독성 간과
- 도구 간 측정 기준 상이로 인한 데이터 신뢰도 저하 및 해석의 왜곡 발생

## Ⅴ. 개선방안
- 다각도 메트릭(복잡도+커버리지+중복도)의 복합적 분석을 통한 균형적 평가
- 전사적 표준 메트릭 기준 수립 및 도구 설정(Rule-set)의 일관성 유지

## Ⅵ. 전망
- AI 기반의 코드 품질 예측 모델 결합으로 결함 발생 가능 구간 사전 탐지
- CSF: 메트릭을 통제가 아닌 개선을 위한 가이드로 활용하는 조직 문화 조성
