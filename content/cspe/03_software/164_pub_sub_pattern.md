## Ⅰ. 개요
- **정의**: 발행자가 토픽에 메시지를 게시하면 구독자 전원에게 브로드캐스트하는 메시징 패턴
- **배경/필요성**: Point-to-Point 큐(163 참조)는 1:1 전달이므로 1:N 이벤트 전파 구조가 필요함
- **비유**: 라디오 방송국이 주파수(토픽)로 송출하면 청취자 전원이 수신하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 이벤트 기반 아키텍처 패턴 | 토픽 기반 1:N 팬아웃 | Message Queue(163 참조)와 차이 명시 |

> 요약: 토픽 기반으로 1:N 메시지를 비동기 팬아웃하는 메시징 패턴임

## Ⅱ. 구성요소
```text
Publisher --+--> [Topic A] --+--> Subscriber 1
            |                +--> Subscriber 2
            +--> [Topic B] ----> Subscriber 3
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Publisher | 토픽에 메시지를 게시하는 발행자 | 방송국 |
| Topic | 메시지를 분류·라우팅하는 논리 채널 | 라디오 주파수 |
| Subscriber | 관심 토픽을 구독하여 메시지를 수신하는 소비자 | 청취자 |
| Broker | 토픽 관리·메시지 배포를 중개하는 서버 | 송신탑 |

> 요약: Publisher-Topic-Subscriber-Broker 4요소로 팬아웃 통신을 수행함

## Ⅲ. 절차
```text
Publisher 게시 --> Broker 라우팅 --> Topic 매칭 --> Subscriber 전달
      |                |               |               |
      v                v               v               v
   메시지 생성     토픽별 분류     구독 목록 조회    병렬 배포
```
- 1단계: Publisher가 메시지를 특정 토픽으로 게시함
- 2단계: Broker가 메시지를 수신하여 토픽별로 분류함
- 3단계: 해당 토픽의 구독자 목록을 조회함
- 4단계: 모든 구독자에게 메시지를 병렬로 전달함

> 요약: 게시-분류-매칭-전달 4단계로 1:N 메시지 배포를 수행함

## Ⅳ. 문제점
- 메시지 순서 미보장: 다수 구독자에게 병렬 전달 시 수신 순서가 상이할 수 있음
- 구독자 장애 시 유실: 오프라인 구독자에게 메시지가 전달되지 않을 수 있음
- 팬아웃 부하: 구독자 수 증가에 비례하여 Broker 네트워크 부하가 증가함

> 요약: 순서 미보장·오프라인 유실·팬아웃 부하가 주요 한계임

## Ⅴ. 개선방안
1. 단기: 파티션 내 순서 보장 + 시퀀스 번호 부여로 순서 문제 완화
2. 중기: 메시지 영속화 + 오프셋 관리로 오프라인 구독자 재수신 지원
3. 장기: 계층적 브로커 클러스터링으로 팬아웃 부하를 분산

> 요약: 순서 보장-영속화-클러스터 분산 순으로 개선함

## Ⅵ. 전망
- 발전 방향: 이벤트 드리븐 아키텍처(EDA)의 핵심 통신 패턴으로 확산 중임
- 기술사적 판단: MSA·서버리스 환경에서 서비스 간 느슨한 결합의 표준 방식임
- 기술사 제언: 메시지 보장 수준·토픽 설계 전략을 도메인 이벤트 단위로 수립할 필요
