## Ⅰ. 개요
- 정의: 사용자 프로그램이 커널에 보호된 자원이나 서비스를 요청하기 위한 인터페이스
- 배경: 사용자 공간(User Space)과 커널 공간(Kernel Space)을 분리하여 시스템 보안성 확보
- 출제 의도: 모드 전환(Mode Switch) 메커니즘과 트랩(Trap) 처리 과정의 정확한 이해

## Ⅱ. 구성요소
```
[ User App ] --(Call API)--> [ Standard C Library ]
                                    | (Trap/Interrupt)
[ Kernel   ] <---(Syscall Table)--- [ Syscall Handler ]
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| API | 시스템 호출을 래핑하여 사용하기 쉽게 만든 함수군 (POSIX 등) | 메뉴판 |
| 시스템 호출 번호 | 요청된 서비스의 종류를 식별하는 고유 번호 | 메뉴 번호 |
| 커널 모드 | 모든 하드웨어 자원에 접근 가능한 높은 권한의 상태 | 관리자 모드 |
> 요약: 안전한 자원 접근을 위해 라이브러리와 핸들러를 거쳐 커널에 도달함.

## Ⅲ. 절차
```
[Invoke API] -> [Reg Load] -> [Trap] -> [Look up Table] -> [Exec] -> [Return]
```
1. 애플리케이션이 `read()`, `fork()` 등 표준 라이브러리 함수를 호출함
2. 필요한 매개변수를 CPU 레지스터에 저장하고 소프트웨어 인터럽트(Trap) 발생
3. CPU 권한이 사용자 모드에서 커널 모드로 전환되며 시스템 호출 핸들러로 제어권 이동
4. 전달된 번호를 기반으로 시스템 호출 테이블에서 해당 커널 함수 실행 및 결과 반환
> 요약: 하드웨어 보호를 위해 엄격히 통제된 경로를 통해서만 자원에 접근함.

## Ⅳ. 문제점
- 원인: 잦은 시스템 호출은 모드 전환 오버헤드를 유발하여 성능 저하의 원인이 됨
- 원인: 매개변수 전달 시 포인터 유효성 검사 미흡으로 인한 커널 패닉(Panic) 가능성

## Ⅴ. 개선방안
- (단기) `vDSO` (Virtual Dynamic Shared Object) 기법으로 빈번한 호출 오버헤드 최적화
- (중기) 사용자 공간 메모리를 직접 접근하는 제로 카피(Zero-copy) 기법 도입
- (장기) `io_uring`과 같은 비동기 시스템 호출 인터페이스를 통한 대량 I/O 처리 효율화

## Ⅵ. 전망
- 클라우드 네이티브 환경에서 보안 강화를 위해 시스템 호출을 필터링하는 `seccomp` 기술 중요성 증대
- 웹어셈블리(Wasm) 등의 런타임과 OS 간의 효율적인 인터페이스(WASI) 표준화가 가속화될 것임
