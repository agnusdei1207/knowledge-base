## 미리 알고가기

- 기능점수 FP는 코드량이 아니라 사용자 관점 기능 규모를 측정하는 방법임
- EI와 EO와 EQ와 ILF와 EIF가 기본 구성 요소임
- 비용 산정과 생산성 비교의 기초 데이터로 자주 쓰인다

## Ⅰ. 개요

- **정의/개념**: 기능점수 FP는 소프트웨어가 사용자에게 제공하는 입력과 출력과 조회와 내부 논리 파일과 외부 인터페이스 파일의 규모를 기준으로 기능 양을 정량화하는 측정 기법임
- **배경/필요성**: 코드 라인 수는 언어와 구현 방식에 따라 달라 비교가 어렵기 때문에, 기술 독립적인 기능 규모 기준이 비용 산정과 생산성 관리에 필요함

## Ⅱ. 특징

- 구현 언어와 무관하게 기능 규모를 비교할 수 있음
- 사용자 관점 기능을 중심으로 산정해 초기 견적에 유리함
- 측정자 해석 차이에 따라 편차가 생길 수 있음
- 기능이 적더라도 복잡한 비기능 요구는 FP에 잘 반영되지 않을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | LOC 기반 | 기능점수 FP |
|:---|:---|:---|
| 기준 | 코드량 | 사용자 기능 규모 |
| 장점 | 측정이 단순 | 언어 독립성과 초기 산정 유리 |
| 한계 | 언어 종속과 재사용 영향 큼 | 측정 규칙과 해석 편차 존재 |
| 적합 환경 | 구현 후 분석 | 요구 기반 견적과 생산성 비교 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| External Input and Output | 사용자 입력과 출력 기능이 시스템 기능 규모의 주요 계산 대상이 됨 |
| External Inquiry | 조회형 상호작용을 별도로 계산해 기능적 응답 범위를 반영함 |
| Internal Logical File | 시스템이 유지하는 내부 데이터 집합 규모를 나타낸다 |
| External Interface File | 외부 시스템과 공유하거나 참조하는 데이터 구조를 기능 규모에 반영함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 식별      | --> | 항목 분류      | --> | 복잡도 가중치 적용 | --> | FP 합산 산정   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기능 식별**: 요구사항에서 사용자 기능을 식별함
2. **항목 분류**: EI와 EO와 EQ와 ILF와 EIF로 분류함
3. **복잡도 가중치 적용**: 유형별 난도를 반영함
4. **FP 합산 산정**: 전체 기능점수를 계산함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 요구 명세가 모호하면 기능 분류와 복잡도 판단이 달라져 FP 편차가 커질 수 있음
   - 해결방안: 측정 기준서와 리뷰를 운영하고 estimation variance와 counting consistency로 검증함
2. 문제: 비기능 요구와 아키텍처 난도가 FP에 충분히 반영되지 않으면 비용 추정이 과소화될 수 있음
   - 해결방안: 별도 보정 계수를 병행하고 nonfunctional adjustment coverage와 estimate accuracy로 검증함
3. 문제: 조직별 생산성 기준이 없으면 FP 값만으로 일정과 비용 의사결정을 하기 어렵다
   - 해결방안: historical productivity baseline을 구축하고 fp per effort baseline quality와 forecast error로 검증함

## Ⅶ. 적용 사례

- 공공 SW 대가산정에서는 기능점수를 사용하고 확인 지표는 counting consistency와 estimate accuracy임
- 대형 SI 제안 단계에서는 FP 기반 초기 견적을 수행하고 확인 지표는 estimation variance와 forecast error임
- 조직 생산성 관리에서는 FP 기준선을 운영하고 확인 지표는 fp per effort baseline quality와 nonfunctional adjustment coverage임

## Ⅷ. 결론

기능점수의 핵심은 소프트웨어를 코드량이 아니라 사용자 기능 규모로 보게 만들어 초기 비용 산정과 조직 생산성 비교의 기준을 제공하는 데 있음.
