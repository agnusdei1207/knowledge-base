## 미리 알고가기

- 기능점수 FP는 코드량이 아니라 사용자 관점 기능 규모를 측정하는 방법임
- EI, EO, EQ, ILF, EIF는 기능점수를 계산할 때 쓰는 기본 기능 항목임
- LOC는 소스 코드 줄 수를 기준으로 규모를 보는 방식임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 기능점수는 사용자 기능 유형, 복잡도 가중치, 언어 독립적 규모 측정을 핵심 축으로 설명함
- 비교표는 LOC와 기능점수의 측정 기준·산정 시점·영향 요인·활용 목적을 대비함
- 공공 SW 견적과 유지보수 변경 산정은 측정 일치율·변경 비용 오차율로 검증함

## Ⅰ. 개요

- **정의/개념**: 기능점수 FP는 외부 입력·출력·조회와 내부·외부 파일을 분류해 사용자 기능 규모를 측정하는 기법임
- **배경/필요성**: 구현 언어와 코드량이 다른 소프트웨어의 규모를 비교하기 위해 사용자 기능 중심의 공통 측정 기준이 필요함

## Ⅱ. 특징

- 구현 언어와 무관하게 기능 규모를 비교할 수 있음
- 요구사항에서 EI·EO·EQ·ILF·EIF를 식별해 구현 전 기능 규모와 대가 산정 근거로 사용함
- 측정자 해석 차이에 따라 결과 편차가 생길 수 있음
- 복잡한 비기능 요구는 기능점수에 충분히 반영되지 않을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | LOC 기반 규모 산정 | 기능점수 FP |
|:---|:---|:---|
| 측정 기준 | 실제 작성된 코드량 | 사용자에게 제공되는 기능 규모 |
| 산정 결과 | 구현 후 집계한 소스 코드 줄 수 | 요구에서 산정한 사용자 기능점수 |
| 주요 한계 | 재사용과 언어 특성 영향을 크게 받음 | 측정 규칙 이해와 해석 일관성이 필요함 |
| 활용 단계 | 구현 결과·유지보수 코드량 분석 | 요구 단계 비용 추정·조직 생산성 비교 |

> 요약: LOC는 구현된 코드량을 집계하고 기능점수는 요구에서 사용자 기능량을 측정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 입력(EI) | 경계 밖의 데이터·제어 정보가 들어와 내부 논리 파일이나 시스템 동작을 변경함 |
| 외부 출력(EO) | 처리·계산으로 만든 데이터·제어 정보를 시스템 경계 밖으로 전달함 |
| 외부 조회(EQ) | 내부 논리 파일을 변경하지 않고 입력 조건에 맞는 데이터를 조회해 반환함 |
| 내부 논리 파일(ILF) | 시스템 경계 안에서 유지하는 사용자 식별 가능 데이터 집합임 |
| 외부 인터페이스 파일(EIF) | 다른 시스템이 유지하고 현재 시스템은 참조만 하는 데이터 집합임 |

> 요약: 사용자 기능을 외부 입력·출력·조회와 내부·외부 파일의 5가지 유형으로 분류함.

## Ⅴ. 원리 및 절차 흐름도

1. **기능 경계 정의**: 측정 대상 시스템과 외부 사용자의 경계를 정함
2. **기능 식별·분류**: 사용자 기능을 EI·EO·EQ·ILF·EIF로 나눔
3. **복잡도 반영**: 기능 유형별 데이터 요소와 참조 파일 수로 복잡도를 정함
4. **FP 합산 산정**: 전체 기능점수를 계산함

> 요약: 시스템 경계를 정한 뒤 5대 기능 유형을 식별하고 복잡도 가중치를 적용해 기능점수를 합산함.

## Ⅵ. 실무 사례

1. 공공 SW 대가산정은 기능 유형 기준서와 교차 검토를 적용하고 측정 일치율·추정 오차율을 확인함
2. 유지보수 계약은 추가·변경·삭제 기능의 점수를 재산정하고 변경 FP 합의율·비용 오차율을 확인함

## Ⅶ. 결론

- 기능점수는 사용자 기능 유형과 복잡도를 기준으로 구현 전 규모와 비용을 산정함
