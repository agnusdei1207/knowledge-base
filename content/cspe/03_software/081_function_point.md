## 미리 알고가기

- 기능점수 FP는 코드량이 아니라 사용자 관점 기능 규모를 측정하는 방법임
- EI, EO, EQ, ILF, EIF는 기능점수를 계산할 때 쓰는 기본 기능 항목임
- LOC는 소스 코드 줄 수를 기준으로 규모를 보는 방식임
- 비기능 요구는 기능점수만으로 충분히 표현되지 않아 별도 보정이 필요할 수 있음

## Ⅰ. 개요

- **정의/개념**: 기능점수 FP는 소프트웨어가 사용자에게 제공하는 입력과 출력과 조회와 내부 논리 파일과 외부 인터페이스 파일의 규모를 기준으로 기능 양을 정량화하는 측정 기법임.
- **배경/필요성**: 코드 라인 수는 언어와 구현 방식에 따라 크게 달라 비교가 어렵기 때문에, 기술 독립적인 기능 규모 기준이 비용 산정과 생산성 비교에 필요함.

## Ⅱ. 특징

- 구현 언어와 무관하게 기능 규모를 비교할 수 있음
- 요구사항에서 EI·EO·EQ·ILF·EIF를 식별해 구현 전 기능 규모와 대가 산정 근거로 사용함
- 측정자 해석 차이에 따라 결과 편차가 생길 수 있음
- 복잡한 비기능 요구는 기능점수에 충분히 반영되지 않을 수 있음

## Ⅲ. 종류 및 비교

| 구분 | LOC 기반 규모 산정 | 기능점수 FP |
|:---|:---|:---|
| 기준 | 실제 작성된 코드량을 기준으로 봄 | 사용자에게 제공되는 기능 양을 기준으로 봄 |
| 산정 결과 | 구현 후 집계한 소스 코드 줄 수 | 요구에서 산정한 사용자 기능점수 |
| 주요 한계 | 재사용과 언어 특성 영향을 크게 받음 | 측정 규칙 이해와 해석 일관성이 필요함 |
| 활용 단계 | 구현 결과·유지보수 코드량 분석 | 요구 단계 비용 추정·조직 생산성 비교 |

> 요약: 기능점수의 가치는 코드를 세는 데서 벗어나 사용자 기능 규모를 공통 기준으로 비교하게 만드는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외부 입력과 출력 | 사용자 입력과 출력 기능이 전체 기능 규모의 큰 비중을 차지함 |
| 외부 조회 | 조회형 상호작용을 따로 계산해 응답 기능 범위를 반영함 |
| 내부 논리 파일 | 시스템이 직접 유지하는 내부 데이터 집합 규모를 나타냄 |
| 외부 인터페이스 파일 | 외부 시스템과 공유하거나 참조하는 데이터 구조를 기능 규모에 반영함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 식별      | --> | 항목 분류      | --> | 복잡도 반영    | --> | FP 합산 산정   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기능 식별**: 요구사항에서 사용자 기능을 찾음
2. **항목 분류**: 입력과 출력과 조회와 파일 항목으로 나눔
3. **복잡도 반영**: 항목별 난도를 반영함
4. **FP 합산 산정**: 전체 기능점수를 계산함

## Ⅵ. 실무 적용 및 유의점

1. 공공 SW 대가산정과 대형 SI 제안 단계에서는 기능점수가 유용하지만 요구 명세가 모호하면 편차가 커지므로 측정 기준서와 교차 리뷰를 함께 운영하고 측정 일치율과 추정 오차율로 확인함
2. 비기능 요구가 큰 금융·플랫폼 시스템에서는 기능점수만으로 비용을 판단하면 과소 추정될 수 있으므로 성능·보안·전환 비용 보정을 함께 두고 비기능 보정 반영률과 최종 비용 오차율로 확인함

## Ⅶ. 결론

기능점수는 소프트웨어를 코드량이 아니라 사용자 기능 규모로 보게 만들어 초기 비용 산정과 생산성 비교의 기준을 제공함.
