## Ⅰ. 개요
- 특정 테스트 목적을 달성하기 위한 입력값, 실행 조건, 예상 결과의 집합임
- 테스트의 재현성을 확보하고 품질 목표 달성 여부를 판단하는 근거가 됨
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 블랙박스 설계 기법, TC 구성요소, 추적성 관리 | 합격 기준이 명시된 시험지 |

## Ⅱ. 구성요소
- 테스트 시나리오, 입력 데이터, 예상 결과, 환경 정보 등으로 구성됨
[ID] -> [입력값] -> [절차] -> [기대결과] -> [결과(P/F)]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 블랙박스 기법 | 요구사항 기반(동등 분할, 경계값 분석, 결정 테이블 등) | 상자 밖에서 두드리기 |
| 테스트 시나리오 | 여러 테스트 케이스의 묶음으로 업무 흐름 중심 검증 | 드라마 대본 |
| 테스트 오라클 | 테스트 결과가 올바른지 판단하는 기준/메커니즘 | 정답지 |
> 요약: 검증 대상, 입력값, 실행 조건, 예상 결과와 합격 기준을 정의함

## Ⅲ. 절차
- 분석부터 폐기까지의 테스트 케이스 생명주기임
[요구사항 분석] -> [설계/작성] -> [검토/확정] -> [실행/유지보수]
- 4단계 설명
1) 설계 기법 적용: 동등 분할·경계값 분석 등으로 대표 입력과 경계 입력을 도출함
2) TC 작성: 식별자, 중요도, 전제조건, 단계별 절차를 명확히 기술함
3) 추적성 매핑: 요구사항 ID와 TC ID를 연결하여 검증 누락을 방지함
4) 형상 관리: 요구사항 변경에 따른 TC 갱신 및 버전 관리를 수행함
> 요약: 요구사항과의 일관성을 유지하며 테스트 자산을 체계화함

## Ⅳ. 문제점
- 요구사항 변경 시 TC 갱신이 누락되어 테스트 신뢰도가 저하됨 (원인: 관리 소홀)
- 테스트 케이스의 위험도와 실행 우선순위가 없으면 회귀 테스트 범위와 시간이 증가함

## Ⅴ. 개선방안
- (단기) 리스크 기반 테스팅(RBT)을 적용하여 고위험군 TC 우선 실행함
- (중기) TMMi(Test Maturity Model integration) 등 테스트 성숙도 모델 도입함
- (장기) MBT(Model-Based Testing)를 통한 테스트 케이스 자동 생성 체계 구축함

## Ⅵ. 전망
- 디지털 트윈 환경에서의 시뮬레이션 기반 TC 설계가 제조/국방 분야에서 확대될 것임
- AI가 코드와 문서를 읽고 TC를 자동 작성/최적화하는 'AI-Driven Testing'이 주류가 될 것임
