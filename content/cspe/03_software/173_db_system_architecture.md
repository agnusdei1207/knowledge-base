## Ⅰ. 개요
- 정의: 데이터베이스의 물리적 저장 구조와 논리적 데이터 처리 방식을 정의한 시스템 구조
- 배경: 데이터 규모 증가에 따른 질의 처리량, 무결성, 가용성 요구 대응
| 구분 | 내용 |
|------|------|
| 출제 의도 | 저장 엔진, 질의 처리기, 버퍼 풀 등의 상호 작용 구조 파악 |

## Ⅱ. 구성요소
  [ Client ] <-> [ Query Engine ] <-> [ Storage Engine ]
                       | (Buffer Pool) |
| 구성요소 | 설명 | 비유 |
|----------|------|------|
| Query Optimizer | 통계와 비용을 기준으로 실행 계획(Plan) 선택 | 내비게이션 |
| Buffer Pool | 디스크 I/O 절감을 위한 메모리 캐시 | 작업대 |
| WAL Log | 장애 복구를 위한 선행 로그 | 블랙박스 |
> 요약: 질의 처리기와 저장 엔진을 분리하고 버퍼·로그로 I/O와 복구를 관리함

## Ⅲ. 절차
  Parse -> Bind -> Optimize -> Execute -> Fetch
1. Parsing: SQL 문법 오류 검사 및 파싱 트리 생성
2. Binding: 카탈로그를 참조하여 테이블/컬럼 유효성 확인
3. Optimization: 통계 기반 실행 비용 계산 및 경로 선택
4. Execution: 엔진을 호출하여 실제 데이터 조회/변경 수행
> 요약: SQL을 구문·객체 단위로 검증하고 비용 기반 실행 계획으로 처리함

## Ⅳ. 문제점
- 데이터량 급증에 따른 단일 서버 디스크 I/O 병목
- 부정확한 통계로 인한 비효율적 조인 순서 선택과 처리 시간 증가

## Ⅴ. 개선방안
- 수평적 확장(Sharding) 및 읽기 분산(Replication) 적용
- 인덱스 최적화 및 파티셔닝을 통한 검색 범위 축소

## Ⅵ. 전망
- 클라우드 네이티브 DB(Aurora 등)의 저장-연산 분리 아키텍처 및 AI 기반 자동 튜닝 보편화
