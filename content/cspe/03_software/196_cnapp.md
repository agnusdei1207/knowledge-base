# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 클라우드 네이티브 애플리케이션의 개발부터 배포, 운영까지 전체 생명주기를 보호하는 통합 보안 플랫폼
- **왜 필요한가**: 클라우드 보안 솔루션이 CWPP, CSPM, CIEM 등으로 너무 파편화되어 있어, 운영자가 전체적인 보안 위협을 한눈에 파악하기 어렵기 때문
- **핵심 직관**: 파편화된 CCTV(보안 도구)들을 하나의 중앙 통제실(CNAPP)로 모아 개발 단계부터 운영까지 전체 보안 상황을 하나로 묶어 관리한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| CSPM (Cloud Security Posture Management) | 클라우드 인프라 설정 오류 탐지 | "문이 제대로 잠겼는지 검사 (AWS S3 퍼블릭 방지)" |
| CWPP (Cloud Workload Protection Platform) | 서버, 가상머신, 컨테이너 자체의 런타임 보호 | "집 안의 금고 튼튼함 검사 (악성코드 차단)" |
| CIEM (Cloud Infrastructure Entitlement Management) | 과도하게 부여된 클라우드 권한을 탐지하고 회수 | "필요 없는 마스터키 압수 (IAM 최소 권한)" |

## 깊이 이해
- **배경·문제의식**: 기업이 클라우드를 도입하면서 인프라 설정 오류 검사(CSPM), 컨테이너 보호(CWPP), 소스코드 취약점 분석 솔루션을 각각 따로 구매했다. 경고(Alert)가 각각의 콘솔에서 울리기 때문에, 해커가 취약한 코드를 통해 컨테이너를 탈취하고 인프라 권한을 획득하는 연속적인 공격을 방어할 수 없었다.
- **작동 원리**: CNAPP는 파편화된 도구들을 단일 플랫폼으로 통합(Convergence)한다. 개발 파이프라인(CI/CD)에 스캐너를 심어 소스 코드와 이미지를 검사(Shift-Left)하고, 런타임 시점에는 인프라 설정(CSPM)과 워크로드 상태(CWPP), 권한(CIEM)을 융합 분석하여 위협의 맥락(Context)을 파악하고 우선순위를 정해준다.
- **비유**: 과거엔 화재경보기, 도난경보기, 가스누출경보기가 제각각 울렸다면, CNAPP는 이 모든 데이터를 모아 "가스 누출로 인한 화재가 금고실로 번지고 있으니, 가스 밸브부터 잠그라"고 알려주는 종합 방재 시스템이다.
- **구체 예시**: 소스코드에 평문 비밀번호가 하드코딩되어 있고(Code), 이 코드를 담은 컨테이너가 취약하며(CWPP), 그 컨테이너가 외부 인터넷에 노출된 설정(CSPM)일 때, CNAPP는 이 3가지를 연관 분석하여 "가장 위험도 높은 위협"으로 식별하고 경고한다.
- **흔한 오해·주의점**: CNAPP는 단순히 여러 솔루션을 한 화면에 보여주는 대시보드가 아니다. 핵심은 여러 계층의 데이터를 연관 분석하여 "공격 맥락(Context)"을 파악하고 위협의 우선순위를 재조정하는 융합(Convergence) 엔진에 있다.

## 연결 개념
- 4C 보안 모델 — CNAPP가 통합하려는 클라우드 네이티브 다계층 방어 대상
- DevSecOps — CNAPP 적용을 위한 개발-운영 파이프라인 철학
- Shift-Left 보안 — 개발 단계로 보안 검증을 앞당기는 CNAPP의 핵심 원리

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CNAPP는 CSPM, CWPP, CIEM 등 파편화된 클라우드 보안 도구를 단일 플랫폼으로 통합하여 애플리케이션 수명 주기 전체를 보호하는 프레임워크임
> 2. **가치**: 사일로(Silo)화된 보안 관리를 타파하고 위협 맥락(Context) 기반의 연관 분석을 통해 보안 가시성과 대응 효율성을 극대화함
> 3. **판단 포인트**: 도입 시 CI/CD 파이프라인 연동(Shift-Left) 역량과 멀티 클라우드 환경 통합 가시성 제공 여부를 중점적으로 평가해야 함

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 보안 통합 플랫폼의 등장 배경 및 요소기술 이해 | CSPM, CWPP, CIEM의 통합, Shift-Left, 위협 연관 분석 | CSPM과 CWPP를 개별적으로 나열하고 통합 분석 의미를 누락 |

> 요약: CNAPP는 클라우드 설정, 런타임 워크로드, 권한 관리를 융합하여 전체 수명 주기 보안을 제공하는 플랫폼임

---

## Ⅰ. 개요 및 필요성

- 개요: 개발부터 운영에 이르는 클라우드 네이티브 애플리케이션의 전체 생명주기를 보호하기 위해 다양한 보안 영역을 단일 뷰로 통합한 플랫폼임
- 배경: 클라우드 보안 솔루션(CSPM, CWPP 등)의 파편화로 인한 위협 탐지 지연 및 경고 피로 누적
- 필요성: 사일로화된 보안 데이터를 융합하여 맥락(Context) 기반의 정확한 위협 식별과 일관된 정책 적용 절실

---

## Ⅱ. 구조 및 구성요소

```text
[개발/빌드] -> [배포] -> [운영/런타임]
    |           |          |
 (SAST/DAST) (Image Scan) (CSPM/CWPP/CIEM)
    +-----------+----------+
          CNAPP 중앙 분석 엔진
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CSPM (설정 관리) | 클라우드 인프라의 설정 오류 및 규제 준수 모니터링 | S3 퍼블릭 접근 탐지 |
| CWPP (워크로드 보호) | 서버, 컨테이너, 서버리스 등 런타임 환경 위협 차단 | 악성코드 및 행위 기반 탐지 |
| CIEM (권한 관리) | 과도한 클라우드 IAM 권한 탐지 및 최소 권한 원칙 적용 | 유령 계정 및 권한 상승 차단 |
| Shift-Left 도구 | 개발 단계의 소스코드 및 인프라 코드(IaC) 취약점 스캔 | 빌드 파이프라인과 통합 |

> 요약: CNAPP는 CSPM(인프라), CWPP(런타임), CIEM(권한)을 중앙 엔진으로 통합하여 가시성을 확보함

---

## Ⅲ. 동작원리 및 흐름도

```text
취약점 스캔 -> 클라우드 설정 수집 -> 권한/행위 분석 -> 맥락 융합 및 대응
```

- 1단계 [개발/빌드 검증]: CI/CD 과정에서 코드(IaC 포함) 및 컨테이너 이미지의 취약점을 사전 스캔
- 2단계 [인프라/권한 수집]: 런타임 환경에서 CSP 인프라 설정(CSPM)과 IAM 권한 정보(CIEM) 실시간 수집
- 3단계 [워크로드 분석]: 컨테이너 및 서버리스 워크로드의 비정상 프로세스 행위(CWPP) 모니터링
- 4단계 [융합 대응]: 수집된 취약점, 설정, 권한 데이터를 연관 분석하여 위협 우선순위를 도출하고 차단

> 요약: 개발 시점의 스캔 데이터와 운영 시점의 런타임 상태를 연관 분석하여 위협의 실제 파급력을 산출함

---

## Ⅳ. 특징
- 가시성 통합: 다수의 보안 콘솔을 하나로 통합하여 보안 팀과 개발/운영 팀 간의 커뮤니케이션 사일로 제거
- 맥락 기반 우선순위화: 단순히 '취약한 패키지 존재'를 넘어 '해당 패키지가 외부 네트워크와 연결되어 있고, 관리자 권한을 가짐'을 융합 분석하여 최우선 조치 가이드
- 생명주기 전반 보호: 배포 이후의 사후 방어뿐만 아니라 개발 시작점부터 보안 검증을 수행하는 엔드투엔드(End-to-End) 커버리지 제공

---

## Ⅴ. 심화 비교 및 적용 판단

| 보안 접근법 | 파편화된 클라우드 보안 (기존) | CNAPP 기반 보안 (현재/미래) | 선택 기준 |
|:---|:---|:---|:---|
| 관리 방식 | CSPM, CWPP, CIEM 개별 운영 | 단일 플랫폼 융합 관리 | 운영 인력 및 복잡도 |
| 위협 분석 | 개별 솔루션의 독립적 알람 | 맥락(Context) 기반 연관 분석 | 알람의 정확도 (오탐률) |
| 방어 시점 | 런타임 위협 사후 탐지 위주 | 빌드-배포-런타임 전 주기 (Shift-Left) | 조기 결함 발견 필요성 |

> 요약: CNAPP는 파편화된 개별 솔루션의 한계를 극복하고 맥락 융합 분석을 통해 오탐을 줄이고 가시성을 극대화함

**리스크·대응 (기본은 불릿):**
- 공급업체 종속성(Vendor Lock-in): 단일 CNAPP 솔루션에 전체 보안이 종속됨 → 멀티 클라우드 및 표준 API(오픈소스 스캐너 연동 등)를 지원하는 개방형 솔루션 선정 (지표: 타사 도구 연동 커버리지)
- 배포 파이프라인 병목: Shift-Left 스캔 시간이 길어져 개발 생산성 저하 → 블록(차단) 모드와 감사(Audit) 모드를 점진적으로 분리 적용 (지표: CI/CD 빌드 소요 시간)

**도입 후 점검 지표 (기본은 불릿):**
- 위협 조치 시간(MTTR): 보안 경고 발생 후 원인 파악 및 조치까지 걸리는 시간 단축률 — ITSM 연동 측정
- 통합 가시성 커버리지: 전체 클라우드 자산 중 CNAPP 에이전트 및 API가 연동된 자산의 비율(목표 100%) — 자산 대장 대조

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 통합 자산 식별: 우선적으로 퍼블릭 클라우드, 쿠버네티스 클러스터 등 섀도우 IT 자산을 포함한 전체 클라우드 자산의 가시성을 CNAPP 대시보드로 통합
2. Shift-Left 자동화: GitLab CI, GitHub Actions 등 개발 파이프라인에 CNAPP 플러그인을 연동하여 IaC 설정 오류(Terraform 스캔) 자동 차단
3. 위험 우선순위 기반 조치: 단순 CVSS 점수가 아닌, 네트워크 노출도와 IAM 권한을 종합 평가한 '실효 위험도' 상위 10% 취약점부터 선제 조치하는 프로세스 수립

**결론 (2줄):**
- 기술사 판단: CNAPP 도입의 성공은 도구의 통합을 넘어, 보안팀(런타임)과 개발팀(빌드)이 동일한 위협 맥락(Context)을 공유하는 프로세스 융합에 있음
- 향후 방향: DSPM(Data Security Posture Management) 기능까지 흡수하여 인프라를 넘어 클라우드 내 데이터 자체의 흐름과 보안까지 통합하는 초연결 보안 플랫폼으로 진화
