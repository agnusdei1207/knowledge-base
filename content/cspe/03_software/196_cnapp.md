## 미리 알고가기

- CNAPP는 개발부터 런타임까지 클라우드 자산·설정·권한·취약점·위협 정보를 통합하는 보안 플랫폼임
- CSPM은 클라우드 자원 설정과 규정 준수 상태를 지속 평가함
- DevSecOps 보안은 소스·의존성·IaC·이미지·파이프라인의 위험을 배포 전에 탐지함
- CWPP는 VM·컨테이너·서버리스·데이터베이스의 취약점과 런타임 위협을 분석함
- 권한 분석은 사람·워크로드 신원의 실제 사용 권한과 과도한 권한 경로를 찾음
- 보안 그래프는 자산·취약점·노출·권한·데이터 관계를 연결해 공격 경로를 구성함

## 작성 근거(검토용)

- CNAPP는 자산 발견, CSPM, DevSecOps, CWPP, 권한, 보안 그래프와 우선순위를 핵심 축으로 설명함
- 비교표는 개별 보안 도구와 CNAPP의 범위·문맥·우선순위·데이터 운영·적합 조건을 대비함
- 절차는 자산·위험 수집부터 관계 분석·우선순위·개발·플랫폼·SOC 조치·재검증으로 이어짐

## Ⅰ. 개요

- **정의/개념**: CNAPP는 코드·파이프라인·클라우드 설정·권한·워크로드 위협을 통합하고 자산 관계와 공격 경로로 위험 우선순위를 정하는 플랫폼임
- **배경/필요성**: 개발·클라우드 제어면·런타임 도구가 각각 생성한 경보의 중복과 문맥 단절을 줄이기 위해 수명주기 통합 분석이 필요함

## Ⅱ. 특징

- 멀티클라우드와 개발 도구에서 자산·설정·취약점·권한·위협 정보를 수집함
- CSPM·DevSecOps·CWPP 결과를 같은 자산과 애플리케이션 문맥으로 연결함
- 외부 노출·취약점·과도한 권한·민감 데이터 관계로 공격 경로와 우선순위를 계산함
- 개발 이슈·클라우드 정책·SOC 대응으로 조치 경로를 나누고 해결 상태를 재검증함

## Ⅲ. 종류 및 비교

| 판단 기준 | 개별 보안 도구 | CNAPP |
|:---|:---|:---|
| 보호 범위 | 코드·설정·권한·런타임을 도구별 분석 | 개발부터 런타임까지 통합 분석 |
| 자산 문맥 | 도구별 자산 ID로 경보 관리 | 클라우드 자산·애플리케이션·소유자 연결 |
| 위험 판단 | 취약점 심각도·규칙 위반별 정렬 | 노출·권한·데이터·위협 관계로 우선순위 산정 |
| 조치 경로 | 도구별 콘솔·티켓에서 처리 | 개발·플랫폼·SOC 워크플로로 분기 |
| 데이터 운영 | 스키마·보존·예외 정책을 별도 관리 | 공통 그래프·정책과 도구별 수집 범위 관리 |
| 적합 조건 | 단일 계층의 전문 분석이 필요 | 다중 클라우드·수명주기 위험을 연결해야 함 |

> 요약: CNAPP는 개발·설정·권한·런타임 위험을 자산 관계로 연결해 조치 우선순위를 정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 자산 발견·인벤토리 | 계정·구독·클러스터·워크로드·데이터·코드 저장소를 식별함 |
| CSPM | 설정 오류·공개 노출·규정 위반을 지속 평가함 |
| DevSecOps 보안 | 소스·의존성·IaC·이미지·파이프라인 위험을 분석함 |
| CWPP | 실행 워크로드의 취약점·행위·위협을 탐지함 |
| 권한·보안 그래프 | 신원·자산·노출·취약점·데이터 관계를 공격 경로로 연결함 |
| 조치 연동 | 개발 티켓·클라우드 정책·SOC 대응과 해결 검증을 연결함 |

```text
코드·IaC·이미지 -> DevSecOps 보안 --+
클라우드 설정 ----> CSPM ------------+-> 보안 그래프 -> 위험 우선순위 -> 조치
워크로드 행위 ----> CWPP ------------+
신원·권한 ----------------------------+
```

> 요약: CNAPP는 각 계층의 위험을 보안 그래프에서 같은 자산·공격 경로로 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
자산 발견 -> 위험 수집 -> 관계 그래프 구성 -> 공격 경로·우선순위 -> 담당 조치 -> 재검증
```

1. **자산 발견**: 클라우드 API와 개발 도구에서 자산·소유자·배포 관계를 수집함
2. **위험 수집**: 설정·취약점·권한·데이터·런타임 위협을 자산에 연결함
3. **관계 분석**: 외부 노출에서 권한·취약점을 거쳐 중요 자산으로 이어지는 경로를 구성함
4. **우선순위 판정**: 도달 가능성·악용 상태·자산 중요도로 조치 순서를 정함
5. **조치·재검증**: 담당 팀에 수정 경로를 전달하고 변경 후 경로가 해소됐는지 확인함

> 요약: 자산별 위험을 공격 경로로 연결하고 도달 가능성과 영향에 따라 조치 후 재검증함.

## Ⅵ. 실무 사례

1. CNAPP는 Kubernetes 워크로드의 노출·취약 이미지·권한을 연결하고 우선 조치 위험 수·해결 시간을 확인함
2. 서버리스 함수 보호는 CNAPP로 코드 의존성과 권한을 연결하고 과권한 함수·미해결 취약점 수를 확인함

## Ⅶ. 결론

- CNAPP는 분리된 보안 경보를 자산·공격 경로·소유자로 연결하고 위험 우선순위의 근거를 검증함
