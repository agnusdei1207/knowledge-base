## 미리 알고가기

- OLTP는 짧은 트랜잭션으로 현재 업무 데이터를 삽입·수정·조회하는 처리 방식임
- OLAP는 이력 데이터를 여러 관점에서 집계·분석하는 처리 방식임
- 사실 테이블(Fact Table)은 측정값과 차원 키를 저장하는 분석 모델의 중심 테이블임
- 차원 테이블(Dimension Table)은 시간·고객·상품처럼 측정값을 분류하는 설명 속성을 저장함
- 스키마 온 라이트는 저장 전에 목표 스키마와 품질 규칙으로 데이터를 변환하는 방식임
- SCD(Slowly Changing Dimension)는 차원 속성 변경 이력을 보존하는 모델링 기법임

## 작성 근거(검토용)

- 데이터 웨어하우스는 통합 이력·차원 모델·스키마 온 라이트·분석 질의를 핵심 판단축으로 선정함
- 비교표는 OLTP DB와 데이터 목적·모델·갱신·질의·일관성·적합 업무를 같은 수준에서 대비함
- 구조와 절차는 원천 데이터가 정제·차원 모델·집계 계층을 거쳐 분석 결과가 되는 흐름을 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 정의와 사례의 분석 축을 일치시킴

## Ⅰ. 개요

- **정의/개념**: 데이터 웨어하우스는 여러 업무 데이터를 공통 기준·시간 이력·차원 모델로 통합해 반복 분석 질의를 제공하는 저장소임
- **배경/필요성**: 운영 트랜잭션 부하와 분석 질의를 분리하고 부서별 지표의 정의를 일치시키기 위해 통합 이력 저장 구조가 필요함

## Ⅱ. 특징

- 고객·상품·조직 같은 주제별로 여러 원천의 코드·단위·키를 통합함
- 적재 시 목표 스키마와 품질 규칙을 적용해 분석 전에 데이터 의미를 확정함
- 사실·차원 모델과 집계 테이블로 기간·조직·상품별 분석 경로를 제공함
- 변경 이력을 보존하고 기준 시점의 상태를 재현해 추세·비교 분석을 지원함
- 열 지향 저장과 파티션 제거로 필요한 열·기간만 읽고 분산 집계를 수행함

## Ⅲ. 종류 및 비교

| 판단 기준 | OLTP 데이터베이스 | 데이터 웨어하우스 |
|:---|:---|:---|
| 데이터 목적 | 현재 업무 트랜잭션 처리 | 통합 이력과 분석 지표 제공 |
| 데이터 모델 | 갱신 중복을 줄인 정규화 모델 | 집계 경로를 단순화한 사실·차원 모델 |
| 갱신 방식 | 행 단위 삽입·수정·삭제 | 배치·증분 적재와 이력 관리 |
| 질의 형태 | 키 기반 단건·짧은 범위 조회 | 기간·차원별 대량 스캔·집계 |
| 일관성 범위 | 한 업무의 트랜잭션 무결성 | 여러 원천의 코드·지표 정의 일치 |
| 적합 업무 | 주문·결제·회원 상태 변경 | 경영 지표·추세·수익성 분석 |

> 요약: 데이터 웨어하우스는 운영 데이터를 공통 차원과 이력으로 통합해 반복 가능한 분석 지표를 제공함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Source·Staging | 업무 DB·파일을 추출하고 원천별 적재 단위로 임시 저장함 |
| ETL·Data Quality | 코드·단위·키를 변환하고 중복·누락·참조 규칙을 검사함 |
| Fact·Dimension | 측정값과 분석 관점을 별도 테이블로 구성해 집계 경로를 만듦 |
| Warehouse Storage | 이력 데이터를 파티션·열 형식으로 저장하고 병렬 질의를 수행함 |
| Semantic Layer·Data Mart | 공통 지표와 부서별 분석 모델을 사용자 질의에 제공함 |
| Metadata·Governance | 스키마·계보·소유자·접근 정책과 지표 정의를 관리함 |

```text
업무 DB·파일 -> Staging·ETL -> Fact·Dimension -> Semantic Layer -> BI
```

> 요약: 원천 데이터는 정제·통합 후 사실·차원 테이블에 이력으로 저장되고 의미 계층을 통해 분석됨.

## Ⅴ. 원리 및 절차 흐름도

```text
원천 추출 -> 품질 검사·표준화 -> 차원 키 매핑 -> 사실·이력 적재 -> 집계 제공
```

1. **원천 추출**: 배치 시점이나 변경 위치를 기준으로 업무 데이터를 Staging에 적재함
2. **표준화**: 데이터 형식·코드·단위를 통일하고 품질 위반 레코드를 분리함
3. **차원 매핑**: 업무 키를 공통 차원 키에 연결하고 속성 변경 이력을 반영함
4. **사실 적재**: 측정값과 차원 키를 적재하고 파티션·집계 구조를 갱신함
5. **분석 제공**: 의미 계층이 공통 지표를 계산해 BI·보고서 질의에 제공함

> 요약: 데이터 웨어하우스는 원천을 표준화해 공통 차원과 이력 사실로 적재한 뒤 분석 지표로 제공함.

## Ⅵ. 실무 사례

1. 주문 수익 분석은 주문·고객·상품 키를 공통 차원으로 통합하고 적재 소요 시간·대사 차이를 확인함
2. 서버 비용 분석은 사용량 사실과 조직 차원을 연결하고 질의 지연·미매핑 조직 수를 확인함

## Ⅶ. 결론

- 데이터 웨어하우스는 공통 지표·이력 보존·적재 주기·분석 질의와 원천 대사 기준을 함께 설계해야 함
