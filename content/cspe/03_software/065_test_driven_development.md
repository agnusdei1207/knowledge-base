## 미리 알고가기

- TDD는 실패하는 테스트를 먼저 작성한 뒤 최소 구현과 리팩터링을 반복하는 개발 방식임
- Red-Green-Refactor 사이클이 핵심임
- 테스트를 많이 쓰는 것과 TDD는 같지 않음

## Ⅰ. 개요

- **정의/개념**: TDD는 요구를 먼저 실패하는 테스트로 표현하고, 그 테스트를 통과시키는 최소 코드 구현과 구조 개선 리팩터링을 짧은 주기로 반복하는 개발 기법임
- **배경/필요성**: 요구가 자주 바뀌는 환경에서는 코드 변경이 두려우면 개발 속도가 떨어지므로, 회귀를 빠르게 확인하며 설계를 조금씩 다듬는 안전한 개발 사이클이 필요함

## Ⅱ. 특징

- 요구를 실행 가능한 테스트 형태로 구체화함
- 작은 주기 반복으로 설계 과잉을 줄이고 피드백 속도를 높임
- 테스트 품질이 낮으면 개발 속도만 늦추고 보호망 역할은 못할 수 있음
- 리팩터링 문화와 CI가 함께 있어야 장기 효과가 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 사후 테스트 | TDD |
|:---|:---|:---|
| 테스트 시점 | 구현 후 작성 | 구현 전 작성 |
| 장점 | 초기 진입 쉬움 | 요구 명확화와 회귀 보호 강화 |
| 한계 | 설계 피드백 약함 | 학습 비용과 규율 필요 |
| 설계 영향 | 구현 후 검증 중심 | 구현 과정 자체에 설계 피드백 제공 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Failing Test | 요구를 구체 행동으로 표현해 무엇을 만들지 분명히 하게 함 |
| Minimal Implementation | 테스트를 통과할 최소 코드만 작성해 과잉 설계를 억제함 |
| Refactoring Step | 동작을 유지한 채 구조를 개선해 코드 부패를 늦춤 |
| Regression Suite | 누적된 테스트가 이후 변경의 안전망이 되어 지속 개발 속도를 지탱함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 실패 테스트 작성 | --> | 최소 구현      | --> | 테스트 통과    | --> | 리팩터링      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **실패 테스트 작성**: 새 요구를 테스트로 표현함
2. **최소 구현**: 테스트를 통과할 만큼만 코드를 작성함
3. **테스트 통과**: 실행 결과를 확인하며 회귀를 점검함
4. **리팩터링**: 중복과 구조 문제를 정리함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 테스트가 구현 세부에 과도하게 묶이면 리팩터링 때마다 테스트 유지비만 커질 수 있음
   - 해결방안: 행위 중심 테스트 기준을 적용하고 brittle test ratio와 refactoring friction score로 검증함
2. 문제: 도메인 이해 없이 TDD를 형식적으로 적용하면 의미 없는 테스트만 늘어날 수 있음
   - 해결방안: 수용 기준 기반 테스트 설계를 적용하고 assertion quality score와 defect escape rate로 검증함
3. 문제: 느린 테스트 스위트는 TDD 주기를 깨뜨려 개발자가 사이클을 포기하게 만들 수 있음
   - 해결방안: 빠른 단위 테스트 중심 구조를 유지하고 feedback loop time과 flaky test rate로 검증함

## Ⅶ. 적용 사례

- 핵심 도메인 로직 개발에서는 TDD를 적용하고 확인 지표는 defect escape rate와 feedback loop time임
- 레거시 리팩터링 구간에서는 보호 테스트를 먼저 두고 확인 지표는 refactoring friction score와 brittle test ratio임
- 신규 팀 온보딩 교육에서는 TDD 코칭을 수행하고 확인 지표는 assertion quality score와 flaky test rate임

## Ⅷ. 결론

TDD의 핵심은 테스트를 먼저 쓰는 형식이 아니라 변경 전에 요구를 작고 검증 가능한 단위로 분해해 설계와 품질 피드백을 동시에 얻는 데 있음.
