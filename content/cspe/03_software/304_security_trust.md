## Ⅰ. 개요
- 정의: 보안성은 무단 접근·유출·변조를 통제하고, 신뢰성은 정해진 조건과 기간에 기능을 수행할 가능성을 관리함
- 배경: 사이버 공격의 지능화 및 개인정보 보호 강화 추세에 따른 안전성 확보 필요
- 출제 의도: 보안 전술(인증, 인가) 및 결함 방지를 통한 신뢰성 설계 역량 확인

## Ⅱ. 구성요소
- ASCII 구조도
  [User] -> [Authentication] -> [Authorization] -> [Audit]
               (Who)             (What)        (Log)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 기밀성/무결성 | 정보 유출 방지 및 위변조 차단 특성 | 금고/봉인 |
| 심층 방어 | 다중 보안 계층 구성을 통한 침투 지연 | 성벽과 해자 |
| 최소 권한 원칙 | 업무 수행에 필요한 최소한의 권한만 부여 | 출입증 등급 |
> 요약: 식별-인증-인가-감사의 보안 프로세스와 다중 방어 체계를 구축함

## Ⅲ. 절차
- ASCII 흐름도
  Threat Modeling -> Policy Def -> Security Tactic -> Monitoring
- 4단계 설명
1. Threat Modeling: 시스템 취약점 및 위협 시나리오(STRIDE 등) 식별함
2. Policy Def: 데이터 중요도에 따른 보안 정책 및 암호화 수준 정의함
3. Security Tactic: SSL/TLS, RBAC, 침입 탐지 시스템(IDS) 등 적용함
4. Monitoring: 실시간 보안 로그 분석 및 이상 징후 탐지 체계 가동함
> 요약: 위협을 분석하여 정책을 세우고 구체적 전술 적용 및 상시 모니터링 수행함

## Ⅳ. 문제점
- 인증 단계·암호화·권한 검사가 늘어나면 사용자 절차와 처리 지연이 증가할 수 있음

## Ⅴ. 개선방안
- 위험 기반 인증과 세션 정책을 적용하고 암호 연산은 HSM 등 전용 장치로 분리하여 지연을 측정함

## Ⅵ. 전망
- 발전 방향: 제로 트러스트(Zero Trust) 아키텍처 및 AI 기반 지능형 보안 관제 고도화
- CSF: 설계 단계부터 보안을 고려하는 시큐어 SDLC(Security by Design) 정착이 핵심임
