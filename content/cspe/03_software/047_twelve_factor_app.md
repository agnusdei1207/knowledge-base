## Ⅰ. 개요
- 정의: 현대적인 SaaS 앱 구축을 위한 12가지 방법론으로, 이식성과 확장성 극대화가 목적임.
- 출제 의도: 클라우드 네이티브 앱 개발의 표준 가이드라인 준수 여부 및 기술적 배경 이해도 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Codebase ] -> [ Config ] -> [ Backing Services ] -> [ Build/Release/Run ]
  (Stateless)     (Env Var)     (Network Attach)       (Strict Separation)
- 구성요소 표
| 핵심 원칙 | 설명 | 비유 |
| :--- | :--- | :--- |
| Codebase | 하나의 코드 저장소에서 여러 환경(Dev/Prod) 배포 관리 | 원본 마스터 테이프 |
| Config | 설정 정보(DB 주소 등)를 코드와 분리하여 환경 변수에 저장 | 상황별 전용 리모컨 |
| Stateless | 프로세스는 상태를 공유하지 않고 외부 저장소에 저장함 | 공중전화(사용 후 초기화) |
> 요약: 환경에 종속되지 않고 어디서든 즉시 실행 가능한 앱 구조 지향함.

## Ⅲ. 절차
- ASCII 흐름도
  [코드 관리] -> [환경 격리] -> [배포 파이프라인] -> [스케일 아웃]
- 4단계 설명
1. Git 등을 통해 모든 변경 이력을 추적 가능한 단일 코드베이스 유지함.
2. 환경에 따른 차이점을 소스 코드가 아닌 인프라 설정으로 주입함.
3. 빌드, 릴리즈, 실행 단계를 엄격히 분리하여 배포 안정성 확보함.
4. 요청 증가 시 프로세스 모델을 통해 동일 앱을 다수 복제하여 대응함.
> 요약: 개발 환경과 운영 환경의 간극(Dev/Prod Parity)을 최소화하는 과정임.

## Ⅳ. 문제점
- 레거시 적응: 기존 유착된 상태(Stateful) 앱을 12-Factor로 전환 시 구조적 개편 고통 큼.
- 설정 보안: 환경 변수에 민감 정보(비밀번호 등) 노출 시 보안 위험 존재함.

## Ⅴ. 개선방안
- 단계적 리팩토링: 상태 저장 로직을 Redis 등 외부 저장소로 점진적 이전 필요함.
- 시크릿 관리: Vault, AWS Secrets Manager 등 전문 도구를 연동하여 설정 보안 강화함.

## Ⅵ. 전망
- 쿠버네티스 등 현대적 플랫폼의 기본 설계 철학으로 완전히 내재화됨.
- '15-Factor' 등으로 확장되어 보안(Security), 관측성(Observability) 요소가 추가 보완 중임.
- 서버리스 아키텍처 확산에 따라 Stateless 원칙의 중요성이 더욱 강조될 것임.
