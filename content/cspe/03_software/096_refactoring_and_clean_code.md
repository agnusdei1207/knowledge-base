## Ⅰ. 개요
- 외부 동작을 바꾸지 않으면서 내부 구조를 개선하여 코드 가독성과 유지보수성을 높임.
- 클린 코드는 "가독성이 높고 누구나 쉽게 이해할 수 있는 코드"를 지향함.
- 출제 의도: 코드의 악취(Bad Smell) 식별 및 개선 기법 적용 능력 평가.

## Ⅱ. 구성요소
- 클린 코드 5대 원칙
[Readable] | [Meaningful] | [Simple] | [Tested] | [Standard]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 의도 명확화 | 변수, 함수 이름을 통해 그 역할을 즉시 알게 함 | 이름표 붙이기 |
| 함수 최소화 | 한 함수는 한 가지 일만 수행하도록 짧게 작성함 | 단일 업무 전문가 |
| 중복 제거 (DRY) | 동일한 로직이 여러 곳에 나타나지 않게 함 | 복사 붙여넣기 금지 |
> 요약: 기계가 아닌 사람이 읽기 좋은 코드를 만드는 것이 핵심임.

## Ⅲ. 절차
- 리팩토링 수행 과정
[Code Reading] -> [Identify Smells] -> [Apply Technique] -> [Test]

1. 분석: 중복 코드, 긴 메서드, 거대한 클래스 등 "코드의 악취"를 찾음.
2. 기법 적용: 메서드 추출, 변수명 변경, 클래스 분리 등을 수행함.
3. 테스트 실행: 기존의 단위 테스트를 돌려 기능적 변경이 없음을 확인함.
4. 반복: 조금씩 점진적으로 구조를 개선하며 완성도를 높임.
> 요약: 작은 단계를 반복하며 기능을 유지한 채 코드를 깨끗하게 다듬음.

## Ⅳ. 문제점
- 리팩토링 과정에서의 예기치 못한 버그 유입 및 과도한 시간 소요.

## Ⅴ. 개선방안
- 자동화된 테스트 커버리지 확보 및 정기적인 기술 부채(Tech Debt) 상환.

## Ⅵ. 전망
- AI 보조 도구(GitHub Copilot 등)가 클린 코드 규칙 위반을 실시간 교정.
- 코드 품질 지표(Complexity, Coverage) 기반의 자동 리팩토링 에이전트 대두.
