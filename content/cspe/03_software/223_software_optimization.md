## Ⅰ. 개요
- 응답 시간·처리량·CPU·메모리 목표를 충족하도록 알고리즘과 실행 코드를 조정하는 활동임
- 컴파일러의 자동 최적화와 개발자의 수동 코드 튜닝이 병행됨
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 알고리즘 복잡도(Big O), 루프 언롤링, 인라이닝, 캐시 지역성 | 요리 과정의 동선 단축 및 효율화 |

## Ⅱ. 구성요소
- 컴파일 단계의 코드 변환과 알고리즘적 개선으로 구성됨
[컴파일러: 루프/인라이닝] <-> [개발자: 자료구조/공간 복잡도]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 루프 최적화 | Loop Unrolling(반복 횟수 줄임), Loop Fusion(반복문 합침) | 여러 번 가던 심부름을 한 번에 가기 |
| 인라이닝(Inlining) | 함수 호출 대신 본체 코드를 직접 삽입하여 오버헤드 제거 | 전화 대신 옆 사람에게 직접 말하기 |
| 캐시 지역성 | 데이터 접근 시 메모리 계층 구조를 고려하여 캐시 히트율 향상 | 자주 쓰는 물건은 책상 위에 두기 |
> 요약: 반복·함수 호출·메모리 접근을 변환하여 명령 실행과 데이터 이동 비용을 줄임

## Ⅲ. 절차
- 측정 기반의 점진적 최적화 프로세스임
[성능 측정(Base)] -> [병목(Hotspot) 분석] -> [최적화 적용] -> [회귀 테스트]
- 4단계 설명
1) 프로파일링: 함수별 실행 시간과 호출 횟수를 측정하여 병목 구간을 식별함
2) 알고리즘 교체: 시간 복잡도(O(N^2) -> O(N log N))가 낮은 알고리즘으로 대체함
3) 메모리 관리: 객체 생성 최소화 및 재사용(Pooling)을 통해 GC 부하를 줄임
4) 컴파일러 옵션 조정: 대상 아키텍처에 최적화된 컴파일러 플래그(-O3 등) 적용함
> 요약: 기준 성능을 측정하고 병목 구간을 변경한 뒤 성능과 기능 회귀 여부를 비교함

## Ⅳ. 문제점
- 과도한 최적화는 코드 가독성을 떨어뜨리고 유지보수를 어렵게 만듦 (원인: 복잡한 코드)
- 특정 환경에 지나치게 튜닝된 코드는 이식성(Portability)이 저하됨 (원인: 하드웨어 종속)

## Ⅴ. 개선방안
- (단기) 가독성을 해치지 않는 범위 내에서 라이브러리 함수 활용 및 루프 개선함
- (중기) 멀티코어 환경을 활용한 병렬 프로그래밍(SIMD, OpenMP) 적용함
- (장기) 정적 분석 도구 및 AI를 활용한 자동 최적화 코드 추천 시스템 도입함

## Ⅵ. 전망
- 대규모 AI 모델의 실시간 추론을 위한 하드웨어 가속기(NPU) 최적화 기술이 중요해질 것임
- 향후 '지속 가능한 컴퓨팅'을 위한 에너지 대비 성능 최적화가 핵심 가치가 될 전망임
