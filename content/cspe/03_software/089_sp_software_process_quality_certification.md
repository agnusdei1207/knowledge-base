## 미리 알고가기

- SP 인증은 조직의 소프트웨어 개발 프로세스 품질 체계를 평가하는 국내 제도임
- 평가 대상은 단일 산출물보다 조직이 반복 가능한 절차를 실제로 수행하는지 여부임
- 인증 기준과 실제 개발 절차가 일치해야 조직 표준 프로세스로 반복 수행할 수 있음

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- SP 인증은 조직 표준 프로세스, 프로젝트 수행 증적, 품질 보증, 개선 체계를 핵심 축으로 설명함
- 비교표는 산출물 점검과 프로세스 인증의 평가 대상·증거·적용 범위·한계를 대비함
- 개발 조직의 인증 운영은 프로세스 적용률·반복 예외 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: SP 인증은 개발 조직의 요구관리·설계·구현·시험·형상관리 프로세스와 수행 증적을 평가하는 품질 인증 제도임
- **배경/필요성**: 프로젝트별 품질 편차를 줄이기 위해 반복·추적 가능한 조직 표준 프로세스와 수행 증적이 필요함

## Ⅱ. 특징

- 결과물보다 프로세스 수행 체계와 증적 일관성을 중심으로 평가함
- 개발 활동과 지원 활동을 함께 보아 조직 역량의 재현 가능성을 판단함
- 공공과 대형 사업에서 공급자 신뢰도 확보 수단으로 활용됨
- 현업에 맞게 내재화하지 못하면 인증 준비 문서만 늘어날 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 프로젝트 산출물 중심 점검 | SP 프로세스 인증 |
|:---|:---|:---|
| 평가 대상 | 단일 프로젝트 결과물의 완성도를 주로 봄 | 조직 전반의 개발 프로세스 수행 체계를 봄 |
| 평가 결과 | 해당 프로젝트 산출물·결함·수용 상태 | 조직 표준 프로세스의 수행·증적·개선 수준 |
| 주요 한계 | 조직 역량 축적 수준은 판단하기 어려움 | 준비 부담과 증적 관리 비용이 큼 |
| 활용 범위 | 개별 프로젝트 납품·품질 점검 | 조직 개발 역량 증명·표준 프로세스 개선 |

> 요약: 산출물 점검은 개별 프로젝트 결과를 확인하고, SP 인증은 조직 프로세스의 수행·증적·개선 체계를 평가함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프로세스 정의 | 표준 절차와 역할과 산출물을 정리해 조직 공통 기준을 만듦 |
| 수행 증적 | 실제 프로젝트 자료를 통해 표준 프로세스가 현장에서 수행됐는지 보여줌 |
| 품질 보증 활동 | 점검과 시정조치로 프로세스 준수와 개선 순환을 만듦 |
| 개선 체계 | 평가 결과와 현장 피드백을 반영해 프로세스를 주기적으로 보완함 |

> 요약: 조직 표준 프로세스를 프로젝트에 적용하고 수행 증적과 품질 점검 결과를 개선 체계에 반영함.

## Ⅴ. 원리 및 절차 흐름도

1. **표준 정의**: 공통 절차와 역할과 산출물을 정함
2. **프로젝트 적용**: 실제 사업에 프로세스를 수행하고 증적을 남김
3. **증적 평가**: 수행 일관성과 적합성을 심사함
4. **개선 반영**: 부적합 사항과 현장 의견을 표준에 반영함

> 요약: 조직 표준을 프로젝트에 적용해 수행 증적을 평가하고 부적합 사항을 프로세스 개선에 반영함.

## Ⅵ. 실무 사례

1. 공공 SW 개발 조직은 필수 수행 증적을 개발 도구와 연결하고 프로세스 적용률·증적 누락률을 확인함
2. 다사업부 개발 조직은 프로젝트 유형별 예외 규칙을 운영하고 예외 승인률·반복 예외 비율을 확인함

## Ⅶ. 결론

- SP 인증은 조직 표준 프로세스의 반복 수행과 증적·개선 체계를 평가함
