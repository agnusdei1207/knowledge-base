## 미리 알고가기

- SP 인증은 조직의 소프트웨어 개발 프로세스 품질 체계를 평가하는 국내 제도임
- 결과물 품질뿐 아니라 개발 관리와 지원 활동의 반복 가능성을 중시함
- 인증 취득보다 조직 프로세스의 실제 내재화가 더 중요함

## Ⅰ. 개요

- **정의/개념**: SP 소프트웨어 프로세스 품질 인증은 개발 조직이 요구관리와 설계와 구현과 시험과 형상관리 같은 핵심 프로세스를 체계적으로 수행하고 있는지 평가해 프로세스 품질 수준을 인증하는 제도임
- **배경/필요성**: 프로젝트별 개인 역량에만 의존하면 산출물 품질 편차가 커지므로, 반복 가능하고 추적 가능한 개발 프로세스를 조직 차원에서 확보할 필요가 있음

## Ⅱ. 특징

- 결과물보다 프로세스 수행 체계와 증적 일관성을 중심으로 평가함
- 개발과 지원 활동을 함께 보아 조직 역량의 재현 가능성을 판단함
- 공공과 대형 사업에서 공급자 신뢰도 확보 수단으로 활용됨
- 현업에 맞게 내재화하지 못하면 인증 준비 문서만 늘어날 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 프로젝트 산출물 중심 점검 | SP 프로세스 인증 |
|:---|:---|:---|
| 평가 대상 | 단일 프로젝트 결과물 | 조직 전반의 개발 프로세스 |
| 강점 | 단기 품질 확인 | 반복 가능성과 관리 수준 입증 |
| 한계 | 조직 역량 축적 판단 어려움 | 준비 부담과 문서 관리 필요 |
| 활용 목적 | 납품 시점 점검 | 공급 역량과 프로세스 개선 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Process Definition | 표준 프로세스와 역할과 산출물을 정리해 조직 공통 기준을 만든다 |
| Project Execution Evidence | 실제 프로젝트 증적을 통해 정의된 프로세스가 현장에서 수행됐는지 보여준다 |
| Quality Assurance | 점검과 시정조치 활동으로 프로세스 준수와 개선 루프를 만든다 |
| Improvement Mechanism | 평가 결과와 현장 피드백을 반영해 프로세스를 주기적으로 보완한다 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 표준 정의      | --> | 프로젝트 적용   | --> | 증적 평가      | --> | 개선 반영      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **표준 정의**: 공통 절차와 역할과 산출물을 정함
2. **프로젝트 적용**: 실제 사업에 프로세스를 수행하고 증적을 남김
3. **증적 평가**: 수행 일관성과 적합성을 심사함
4. **개선 반영**: 부적합 사항과 현장 의견을 표준에 반영함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 인증 준비를 위해 형식 문서만 늘리면 현장 개발 속도만 저하되고 실제 품질 개선으로 이어지지 않을 수 있음
   - 해결방안: 필수 증적만 표준화하고 process adoption rate와 documentation overhead ratio로 검증함
2. 문제: 표준 프로세스가 프로젝트 특성을 반영하지 못하면 현장 우회가 늘어 평가 신뢰성이 떨어질 수 있음
   - 해결방안: tailoring 규칙을 명문화하고 tailoring compliance와 waiver recurrence rate로 검증함
3. 문제: 인증 후 개선 활동이 멈추면 조직 프로세스가 빠르게 진부화될 수 있음
   - 해결방안: 정기 프로세스 리뷰를 운영하고 corrective action closure rate와 process freshness index로 검증함

## Ⅶ. 적용 사례

- 공공 SI 조직에서는 표준 프로세스를 정비하고 확인 지표는 process adoption rate와 documentation overhead ratio임
- 다사업부 개발 조직에서는 tailoring 규칙을 운영하고 확인 지표는 tailoring compliance와 waiver recurrence rate임
- 품질 보증 조직에서는 인증 이후 개선 회의를 지속하고 확인 지표는 corrective action closure rate와 process freshness index임

## Ⅷ. 결론

SP 인증의 실질 가치는 인증서 획득보다 조직 프로세스를 반복 가능하게 만들고 프로젝트 품질 편차를 줄이는 데 있음.
