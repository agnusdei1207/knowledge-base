# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 가상 메모리 환경에서 물리 메모리(RAM)에 빈 공간이 없을 때, 디스크에서 새 페이지를 가져오기 위해 기존 메모리에 적재된 페이지 중 어떤 것을 쫓아낼지(희생양) 결정하는 전략.
- **왜 필요한가**: 쫓아낸 페이지를 다음 순간에 바로 다시 쓴다면 엄청난 성능 낭비(Page Fault 연쇄)가 일어난다. 앞으로 가장 안 쓸 것 같은 페이지를 골라내어 디스크 I/O를 최소화해야 한다.
- **핵심 직관**: 100권의 책 중 10권만 꽂을 수 있는 책꽂이(RAM). 새 책을 꽂으려면 1권을 버려야 한다. 가장 오랫동안 안 본 책을 버릴지(LRU), 가장 먼저 꽂은 책을 버릴지(FIFO) 결정하는 규칙이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **희생 페이지 (Victim Page)** | 물리 메모리 공간 확보를 위해 디스크 스왑 공간으로 방출(쫓겨남)되기로 결정된 페이지 | "책꽂이에서 버려질 타겟 서적" |
| **벨라디의 모순 (Belady's Anomaly)** | 할당 프레임(책꽂이 칸) 수를 늘렸는데도 페이지 부재(Page Fault)가 오히려 증가하는 기현상 (FIFO에서 발생) | "책꽂이를 넓혔는데 버리는 횟수가 더 늘어남" |
| **참조 비트 (Reference Bit)** | H/W가 페이지 접근 시 1로 세팅하여 '최근 사용 여부'를 표시하는 비트 | "최근에 읽은 책에 꽂아둔 임시 책갈피" |

## 깊이 이해
- **배경·문제의식**: 미래에 어떤 페이지가 호출될지 정확히 알 수 있다면 가장 나중에 쓰일 페이지를 방출하면 되지만(OPT), 미래 예측은 불가능하다. 따라서 과거의 참조 기록(시간, 빈도)을 바탕으로 최선의 휴리스틱을 찾아야 한다.
- **작동 원리 (대표 알고리즘)**:
  - **OPT (Optimal)**: 가장 미래에 참조될 페이지 교체 (이론적 최적, 구현 불가능, 비교 기준).
  - **FIFO (First-In First-Out)**: 메모리에 가장 먼저 들어온 페이지 교체 (단순하나 효율 최악, 벨라디 모순).
  - **LRU (Least Recently Used)**: 가장 오랫동안 참조되지 않은 페이지 교체 (지역성 반영 우수, 리스트 관리 오버헤드 큼).
  - **LFU (Least Frequently Used)**: 참조 횟수가 가장 적은 페이지 교체 (최근 갓 적재된 페이지가 억울하게 방출될 위험).
  - **Clock (NUR, Not Used Recently)**: LRU의 리스트 유지 오버헤드를 없애기 위해, 참조 비트만 돌면서 확인하다 0인 것을 쫓아내는 실용적 근사 기법.
- **구체 예시**: 프로세스가 1->2->1->3->4 페이지 순으로 호출할 때 3칸의 메모리가 있다면, LRU는 1번을 보존하고 가장 안 쓴 페이지를 방출한다. Windows나 Linux 커널은 완벽한 LRU 대신 Clock 알고리즘의 변형(Second Chance 등)을 실제 구현체로 쓴다.
- **흔한 오해·주의점**: LRU가 가장 완벽해 보이지만, 링크드 리스트나 스택을 유지하기 위한 하드웨어/소프트웨어 오버헤드가 너무 커서 순수 LRU는 가상 메모리에 거의 쓰이지 않는다. 대부분 참조 비트를 활용한 Clock(NUR) 계열로 근사(Approximation)하여 사용한다.

## 연결 개념
- (015 프로세스 스레싱 참조) 페이지 교체가 과도하게 일어날 때의 성능 붕괴
- (018 워킹 셋 참조) 참조 기록을 기반으로 지역성을 보장하는 프레임 할당

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 페이지 교체 알고리즘은 물리 메모리 고갈 시 희생 페이지(Victim)를 선정하여 가상 메모리의 Page Fault 비율을 통제하는 휴리스틱 결정 로직이다.
> 2. **가치**: 프로그램의 시간적·공간적 지역성(Locality)을 최대한 반영하여, 불필요한 디스크 I/O 스왑을 억제하고 CPU 이용률을 유지한다.
> 3. **판단 포인트**: 미래 예측(OPT)이 불가능한 현실에서, 구현 오버헤드가 큰 순수 LRU 대신 H/W 참조 비트 기반의 NUR(Clock) 알고리즘이 실무적 표준으로 사용된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 가상 메모리 병목 통제 원리 및 교체 기법 특성 이해 | OPT, FIFO, LRU, LFU, Clock 기법의 메커니즘과 장단점 비교 | LRU를 실무에서 그대로 쓴다고 단정하는 오류 (근사 사용이 정답) |
| 각 알고리즘의 한계와 지역성(Locality) 상관성 파악 | FIFO의 벨라디 모순(Belady's Anomaly), LRU의 시간적 지역성 반영 | 평가 기준(오버헤드 vs 교체 효율) 누락 |

> 요약: 각 교체 알고리즘이 희생양을 선택하는 기준과 오버헤드를 비교하고, 실제 운영체제에서 Clock(NUR) 알고리즘이 선택되는 이유를 구조적으로 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 페이지 교체 알고리즘은 물리 메모리에 빈 프레임이 없을 때, 디스크로 방출할 희생 페이지를 결정하여 Page Fault 비율을 최소화하는 메모리 관리 전략
- 배경: 제한된 물리 메모리에 다중 프로세스를 적재하기 위해 요구 페이징(Demand Paging) 기법을 사용하므로 필연적으로 페이지 공간 고갈 발생
- 필요성: 교체 알고리즘이 비효율적이면 곧바로 사용할 페이지를 쫓아내어 시스템 스레싱(Thrashing)을 유발하므로, 지역성 기반의 최적 예측 메커니즘 필수

---

## Ⅱ. 구조 및 구성요소

```text
CPU 참조 요구 -> [MMU 검사] -> Page Fault 발생
  -> 물리 메모리(Full) -> [교체 알고리즘 구동] -> Victim 페이지 선정
  -> [디스크 Swap 영역]으로 방출(Swap-out) 및 새 페이지 적재(Swap-in) -> 페이지 테이블 갱신
```

| 기법 분류 | 알고리즘 | 희생 페이지 선정 기준 |
|:---|:---|:---|
| 최적/기준 | **OPT** (Optimal) | 앞으로 가장 오랫동안 사용되지 않을 페이지 (구현 불가, 이론적 지표) |
| 단순 큐 | **FIFO** | 메모리에 가장 먼저 적재된(오래 머문) 페이지 |
| 과거 시간 기반 | **LRU** (Least Recently) | 과거 가장 오랫동안 참조되지 않은 페이지 |
| 참조 빈도 기반 | **LFU** (Least Frequently)| 적재 후 참조된 횟수가 가장 적은 페이지 |
| H/W 지원 실용화 | **Clock / NUR** | 참조 비트(Reference Bit)가 0인 페이지 중 하나를 원형 탐색 |

> 요약: 알고리즘 설계는 과거의 참조 이력(시간, 빈도)을 통해 미래의 지역성을 예측하는 과정이며, 관리 오버헤드를 줄이는 것이 관건이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
희생 대상 탐색 루프 (Clock 알고리즘 기준) -> 포인터가 가리키는 페이지의 참조 비트 확인
  / 참조 비트 == 1 -> 비트를 0으로 초기화 (Second Chance 부여) -> 포인터 다음 이동
  / 참조 비트 == 0 -> 희생 페이지(Victim) 확정 -> 루프 종료 -> 디스크 Swap 수행
```

- 1단계 [부재 및 락]: Page Fault 발생 시 커널이 개입하여 메모리 할당 락 획득
- 2단계 [Victim 선정]: 정책(LRU의 스택 최하단, FIFO 큐의 헤드, Clock의 원형 탐색)에 따라 방출할 프레임 식별
- 3단계 [Dirty Bit 검사]: 선정된 페이지가 적재 후 수정(Write)되었는지 확인하여, 수정되었으면 디스크에 기록(Swap-out)
- 4단계 [새 데이터 적재]: 빈 프레임에 디스크의 새 페이지를 적재(Swap-in)하고 페이지 테이블의 유효 비트 갱신

> 요약: 교체 흐름에서 중요한 것은 단순 방출이 아니라, Dirty Bit를 확인하여 불필요한 디스크 쓰기 연산을 생략하는 것이다.

## Ⅳ. 비교 (LRU vs FIFO vs Clock)

| 비교 축 | LRU (Least Recently Used) | FIFO (First-In First-Out) | Clock (NUR, Not Used Recently) | 선택 기준 |
|:---|:---|:---|:---|:---|
| 반영 원리 | 시간적 지역성 (최근 사용 중시) | 적재 순서 (지역성 무시) | H/W 참조 비트 근사 (실용적 LRU) | 페이지의 활용 패턴 반영 여부 |
| 구현 자료구조 | Linked List, Stack, Counter | Queue (단순 배열) | 원형 리스트 (Circular Array) + 포인터 | H/W 지원 요구 및 S/W 연산 비용 |
| 성능 오버헤드 | 메모리 참조마다 갱신 비용 큼 | 오버헤드 매우 낮음 | 참조 비트만 돌면 되므로 오버헤드 낮음 | 문맥 교환 시 지연 시간에 미치는 영향 |
| 주요 한계점 | S/W 갱신 오버헤드로 가상 메모리에 부적합 | 벨라디의 모순(Belady's Anomaly) 발생 | 완벽한 최신 참조 순서를 100% 보장 못 함 | 성능 vs 구현 복잡도의 트레이드오프 |

> 요약: 성능만 보면 LRU가 우수하지만 모든 메모리 참조를 OS가 추적할 수 없으므로, H/W가 세팅해주는 참조 비트에 의존하는 Clock 알고리즘을 실무로 선택한다.

## Ⅴ. 심화 비교 및 적용 판단

**리스크·대응:**
- 벨라디의 모순(Belady's Anomaly): FIFO 계열 사용 시 프레임을 더 주어도 오히려 Fault가 증가하는 기현상 발생 → 스택 성질(Stack Property)을 가지는 LRU나 LFU 기반, 혹은 이를 보완한 Clock 변형(Second Chance) 알고리즘 적용 (지표: 프레임 대비 Page Fault 반비례 곡선)
- Clock 루프 무한 탐색 지연: 전체 페이지가 1(최근 참조)이면 희생자를 찾기 위해 전체 메모리를 한 바퀴 다 돌며 0으로 깎는 지연 발생(O(N) 순회) → Two-Hand Clock 알고리즘으로 한 손은 미리 비트를 0으로 지우고, 다른 손이 뒤따라가며 0인 프레임을 회수하여 탐색 지연 축소

**도입 후 점검 지표:**
- 성능: 프로세스별 Page Fault Rate — `sar` 또는 `vmstat` 명령어로 시스템 전반의 교체 빈도 확인
- 품질: Swap I/O 대역폭 점유율 — 디스크 병목 발생 여부 모니터링

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ARC(Adaptive Replacement Cache) 적용: LRU(최근성)와 LFU(빈도)를 동적으로 결합한 캐시 교체 알고리즘(ZFS 등에서 사용)을 도입하여, 순차적 대용량 읽기(Scan) 시 캐시가 오염되는 현상(Cache Pollution) 방지
2. 리눅스 커널의 Active/Inactive 리스트: 완벽한 LRU 대신, 참조된 페이지(Active)와 후보 페이지(Inactive) 리스트를 나누고, Inactive 리스트의 꼬리에서만 희생 페이지를 고르는 실무형 교체 정책 운영
3. Dirty Page 백그라운드 플러시: 페이지 교체 순간 디스크 쓰기(Swap-out)를 기다리면 지연이 길어지므로, 데몬(예: `pdflush`)이 주기적으로 수정된 페이지를 미리 디스크에 동기화시켜 Clean 프레임 확보

**결론 (2줄):**
- 기술사 판단: 교체 알고리즘 선택은 1%의 적중률 향상보다 99%의 참조 시 발생하는 자료구조 갱신 오버헤드를 통제하는 것이 중요하므로, Clock 기반의 하드웨어 지원 근사(Approximation) 기법이 정답이다.
- 향후 방향: 인메모리 DB나 AI 워크로드처럼 교체 자체가 시스템 마비를 초래하는 환경에서는, OS의 페이징을 우회하여 애플리케이션 스스로 메모리를 직접 제어하는 Direct I/O 및 Bypass 기법이 증가하고 있다.
