## Ⅰ. 개요
- **정의**: 물리 메모리가 가득 찼을 때 어떤 페이지를 제거할지 결정하는 알고리즘
- **배경/필요성**: 가상 메모리(016 참조) 환경에서 Page Fault 시 빈 프레임이 없으면 기존 페이지를 교체해야 하므로 교체 대상 선정 기준이 필요함
- **비유**: 가득 찬 책꽂이에서 가장 안 읽는 책을 빼고 새 책을 꽂는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 교체 알고리즘 비교 분석 | OPT·LRU·FIFO·Clock 특성 차이 | Belady's Anomaly 발생 조건(FIFO) 언급 필요 |

> 요약: 물리 메모리 부족 시 교체 대상 페이지를 선정하여 페이지 폴트율을 최소화하는 알고리즘임

## Ⅱ. 구성요소
```text
Page Fault 발생 --> 빈 프레임 확인 --> 교체 알고리즘 --> 희생 페이지 선정 --> 교체
                      |                                        |
                   있음: 즉시 적재                      dirty면 디스크 기록
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| OPT | 미래에 가장 오래 사용되지 않을 페이지 교체 (이론적 최적) | 미래를 아는 사서 |
| LRU | 가장 오래 전에 사용된 페이지 교체 | 가장 오래 안 읽은 책 제거 |
| FIFO | 가장 먼저 적재된 페이지 교체 | 줄 선 순서대로 퇴장 |
| Clock(NRU) | 참조 비트 기반 원형 리스트 순회로 교체 대상 선정 | 시계 바늘이 가리키는 미사용 칸 |

> 요약: OPT(이론), LRU(실용), FIFO(단순), Clock(근사) 4가지가 대표 알고리즘임

## Ⅲ. 절차
```text
Page Fault --> 빈 프레임? --N--> 교체 대상 선정 --> Swap Out --> Swap In
                  |
                 Y --> 즉시 적재
```
- 1단계: Page Fault 발생 시 OS가 인터럽트 처리 루틴 진입
- 2단계: 빈 프레임 존재 여부 확인 (Free Frame List 검사)
- 3단계: 빈 프레임 없으면 교체 알고리즘으로 희생 페이지 선정, dirty 시 디스크 기록
- 4단계: 희생 프레임에 새 페이지 적재 후 페이지 테이블·TLB 갱신

> 요약: 폴트 발생-프레임 확인-희생 선정-적재 갱신 4단계로 교체를 수행함

## Ⅳ. 문제점
- Belady's Anomaly: FIFO에서 프레임 수 증가 시 오히려 폴트율 상승 — 적재 순서만 고려하기 때문
- LRU 구현 비용: 매 참조마다 타임스탬프 갱신 필요 — 하드웨어 오버헤드 증가
- Thrashing: 교체 빈도 과다 시 CPU가 페이지 교체에만 시간 소모 — 유효 처리량 급감

> 요약: Belady's Anomaly, LRU 구현 비용, Thrashing이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 스택 알고리즘(LRU 계열) 사용으로 Belady's Anomaly 원천 회피
2. 중기: Clock 알고리즘 등 참조 비트 기반 근사 LRU 적용으로 구현 비용 절감
3. 장기: 워킹셋(018 참조) 기반 프레임 할당으로 Thrashing 예방

> 요약: 스택 알고리즘, 근사 LRU, 워킹셋 기반 할당 순으로 개선 필요

## Ⅵ. 전망
- 발전 방향: ML 기반 페이지 접근 패턴 예측으로 교체 정확도 향상이 연구되고 있음
- 기술사적 판단: NVM(비휘발성 메모리) 계층 추가로 교체 비용 구조가 재편될 전망임
- 기술사 제언: 메모리 계층별 접근 비용을 고려한 계층 인식(tier-aware) 교체 정책 설계가 필요함
