## 미리 알고가기

- 페이지 교체는 메모리 부족 시 어떤 페이지를 내보낼지 결정하는 정책임
- page fault는 필요한 페이지가 메모리에 없을 때 발생함
- 목표는 fault를 줄이면서도 구현 비용과 오버헤드를 관리하는 것임

## 작성 근거(검토용)

- FIFO·LRU·LFU·OPT를 희생 기준·메타데이터·지역성·한계·활용 역할로 비교함
- 페이지 폴트 후 빈 프레임·희생 페이지·더티 기록·적재 순서를 실제 절차로 유지함
- 운영체제 사례는 Clock 근사와 작업 집합 조정으로 대표 정책을 검증함

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 물리 메모리가 가득 찬 상태에서 새로운 페이지를 적재하기 위해 기존 페이지 중 어떤 것을 희생할지 결정하는 메모리 관리 정책임
- **배경/필요성**: 물리 메모리에 새 페이지를 적재할 공간이 없을 때 페이지 폴트와 디스크 I/O를 줄일 희생 페이지 선택 기준이 필요함

## Ⅱ. 특징

- 실행 전에 미래 참조 순서를 알 수 없으므로 적재 순서·최근성·참조 빈도로 교체 대상을 추정함
- 최근·반복 참조 패턴을 교체 기준에 반영하면 다시 참조할 페이지의 퇴출을 줄일 수 있음
- 구현 복잡도와 하드웨어 지원 수준에 따라 적용 가능 정책이 달라짐
- 반복 참조할 페이지를 계속 퇴출하면 페이지 폴트와 교체 I/O가 실행시간을 점유함

## Ⅲ. 종류 및 비교

| 판단 기준 | FIFO | LRU | LFU | OPT |
|:---|:---|:---|:---|:---|
| 선택 기준 | 먼저 들어온 페이지 | 가장 오래 미사용 페이지 | 사용 빈도 낮은 페이지 | 미래에 가장 늦게 쓰일 페이지 |
| 반영 정보 | 적재 순서 | 최근 참조 시점 | 참조 횟수 | 미래 참조 시점 |
| 한계 | Belady anomaly 가능 | 구현 비용 큼 | 초기 빈도 편향 가능 | 실제 구현 불가 |
| 활용 의미 | 단순 기준선 | 실무 근사 목표 | 특수 패턴 분석 | 비교용 상한선 |

> 요약: FIFO는 적재 순서, LRU는 최근성, LFU는 빈도, OPT는 미래 재참조 시점으로 희생 페이지를 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프레임 집합 | 메모리에 적재된 페이지와 교체 후보를 관리함 |
| 참조 이력 | 최근 사용 시점·빈도·참조 비트를 저장함 |
| 희생 페이지 선택기 | 정책 기준으로 내보낼 페이지를 결정함 |
| 페이지 폴트 처리기 | 더티 페이지 기록과 신규 페이지 적재를 수행함 |

> 요약: 참조 이력과 더티 상태를 이용해 희생 페이지를 선택하고 페이지 폴트 처리기가 교체함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 페이지 참조     | --> | 적중 여부 확인 | --> | 희생 페이지 선택 | --> | 교체 및 갱신   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **페이지 참조**: 프로세스가 특정 가상 페이지를 요구함
2. **적중 여부 확인**: 메모리에 있으면 참조 정보만 갱신함
3. **희생 페이지 선택**: 빈 프레임이 없으면 정책에 따라 내보낼 페이지를 고름
4. **교체 및 갱신**: 더티 페이지를 기록하고 신규 페이지와 참조 이력을 갱신함

## Ⅵ. 실무 사례

1. 범용 운영체제는 LRU를 Clock으로 근사하고 교체 처리시간과 주요 페이지 폴트율을 확인함
2. 메모리 과할당 서버는 프레임 수별 폴트 곡선으로 작업 집합을 조정하고 swap I/O와 처리량을 확인함

## Ⅶ. 결론

- 페이지 교체는 작업 집합의 최근성·빈도와 참조 이력 관리·더티 페이지 기록 비용으로 정책을 선택함
