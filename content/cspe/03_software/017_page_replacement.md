# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 페이지 교체 알고리즘은 **요구 페이징에서 물리 프레임이 모두 차 있는데 새 페이지 폴트가 발생했을 때, 어떤 페이지를 디스크로 내보내(victim) 자리를 비울지 결정하는 규칙**으로, FIFO·LRU·LFU·Clock·Optimal이 대표적이다.
- **왜 필요한가**: 프레임 수는 유한하므로 교체는 불가피한데, 나쁜 선택은 곧 다시 참조될 페이지를 내보내 폴트를 연쇄시킨다. 미래 참조를 잘 예측하는 알고리즘일수록 폴트율(=성능)이 낮아진다.
- **핵심 직관**: 좁은 책상에 책이 꽉 찼을 때 새 책을 놓으려면 한 권을 치워야 한다. "가장 오래 안 볼 책"을 치우면 최선이지만 미래를 모르니, "가장 오래 안 본 책"(LRU)처럼 과거로 미래를 근사한다.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 답안용에 나오는 표기를 비유와 함께 먼저 세운다. 가상 메모리·페이지·프레임의 기본 개념은 016 참조.

| 용어/표기 | 의미 | 비유·예 |
| --- | --- | --- |
| 페이지 교체 (상위 키워드) | 프레임이 꽉 찼을 때 내보낼 페이지를 고르는 규칙 | 책상 꽉 찼을 때 치울 책 고르기 |
| Victim 페이지 | 교체 대상으로 선택되어 디스크로 내려가는 페이지 | 치워지는 책 |
| 페이지 폴트율 | 전체 참조 중 폴트가 난 비율 | 서가에서 책 꺼낸 횟수 비율 |
| FIFO | 가장 먼저 들어온 페이지를 교체 | 오래전에 놓은 책부터 치움 |
| LRU (Least Recently Used) | 가장 오래 참조되지 않은 페이지를 교체 | 가장 오래 안 펼친 책 치움 |
| LFU (Least Frequently Used) | 참조 횟수가 가장 적은 페이지를 교체 | 가장 적게 본 책 치움 |
| Clock (2차 기회) | 참조비트를 원형으로 돌며 0인 페이지를 교체 | 시계 바늘 돌며 안 본 표시 찾기 |
| 참조비트 (Reference bit) | 최근 참조되면 1로 세팅되는 1비트 플래그 | 책에 붙인 "봤음" 스티커 |
| Optimal (OPT/Belady) | 앞으로 가장 오래 안 쓸 페이지를 교체(이론상 최적) | 미래를 다 아는 완벽한 선택 |
| Belady 이상현상 | 프레임을 늘렸는데 폴트가 오히려 느는 역설 | 책상을 넓혔는데 더 자주 꺼냄 |
| 지역성 (Locality) | 최근 참조한 것 근처를 다시 참조하는 경향 | 방금 본 책 근처를 또 봄 |

## 깊이 이해
- **배경·문제의식**: 요구 페이징에서 물리 메모리는 유한하므로, 새 페이지를 올리려면 기존 페이지를 반드시 내보내야 한다. 어떤 페이지를 내보내느냐가 이후 폴트 횟수를 좌우한다. 이상적으로는 "앞으로 가장 오래 안 쓸 페이지"(Optimal)를 내보내야 폴트가 최소지만, 미래 참조열을 알 수 없어 과거 이력으로 근사한다.
- **작동 원리(어떻게+왜)**: FIFO는 적재 순서만 보므로 구현이 쉽지만 자주 쓰는 페이지도 오래됐다고 내보내 비효율적이다. LRU는 지역성 가정("최근 안 쓴 건 앞으로도 안 쓸 확률이 높다") 위에서 과거로 미래를 근사해 폴트율이 Optimal에 가깝지만, 매 참조마다 시간 기록이 필요해 비싸다. Clock은 참조비트 1개로 LRU를 값싸게 근사한다 — 바늘이 돌며 참조비트 1은 0으로 리셋하고 지나가고, 0을 만나면 그 페이지를 교체해 "2차 기회"를 준다.
- **비유**: 책상(프레임)에 책이 꽉 찼을 때, FIFO는 "오래전에 올린 책"을 무조건 치우고(지금 자주 봐도), LRU는 "가장 오래 안 펼친 책"을 치운다. Clock은 각 책에 "최근 봤음" 스티커를 붙여 두고 바늘을 돌리며 스티커 없는 책을 치우되, 스티커 있는 책은 스티커만 떼고 한 바퀴 기회를 준다.
- **구체 예시**: 참조열 1,2,3,4,1,2,5,1,2,3,4,5, 프레임 3개일 때 FIFO는 폴트 9회, LRU는 10회, Optimal은 7회다. FIFO에서 프레임을 3→4로 늘리면 폴트가 9→10으로 오히려 늘어나는 Belady 이상현상이 관찰된다. LRU·Optimal은 스택 알고리즘이라 이 역설이 없다.
- **흔한 오해·주의점**: (1) **프레임을 늘리면 폴트가 항상 준다고 단정하면 안 된다** — FIFO에서는 Belady 이상현상으로 반례가 있다. (2) **LRU ≠ Optimal** — LRU는 과거 근사라 특정 패턴(순환 참조)에서 나쁠 수 있다. (3) Clock은 LRU 자체가 아니라 값싼 근사이며, 실제 OS(리눅스 등)가 이 계열을 쓴다.

## 연결 개념
- 가상 메모리·요구 페이징(016 참조) — 페이지 교체가 일어나는 전제 구조
- 워킹셋·페이지 폴트 빈도(018 참조) — 전역 교체가 스레싱으로 번지지 않게 프레임을 배분
- 프로세스 스레싱(015 참조) — 교체가 과도해질 때의 성능 붕괴

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 페이지 교체는 프레임 포화 시 victim을 고르는 규칙이며, 미래 참조 예측 정확도가 폴트율을 결정함.
> 2. **가치**: Optimal은 이론적 하한, LRU는 지역성 기반 실용 근사, Clock은 값싼 하드웨어 구현으로 각자 역할이 있음.
> 3. **판단 포인트**: FIFO는 Belady 이상현상 위험이 있어 지양하고, 실무는 Clock·LRU 근사를 채택함.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
| --- | --- | --- |
| 알고리즘별 원리·폴트 계산 | FIFO·LRU·Optimal 참조열 트레이스 | 참조열 계산 오류·victim 오지정 |
| Belady 이상현상 | FIFO에서 프레임↑에도 폴트↑ | 모든 알고리즘에서 발생한다고 단정 |
| 실무 선택 근거 | Clock·2차 기회의 저비용 근사 | LRU를 그대로 구현 가능하다고 단정 |

> 요약: 알고리즘별 폴트 트레이스와 Belady 이상현상을 정확히 제시하고, 스택 알고리즘·Clock 근사로 실무 선택을 논함.

## Ⅰ. 개요 및 필요성
- 개요: 프레임이 꽉 찬 상태의 페이지 폴트에서 내보낼 victim을 선택하는 규칙임
- 배경: 프레임은 유한해 교체가 불가피하며, 선택이 나쁘면 곧 쓸 페이지를 내보내 폴트가 연쇄됨
- 필요성: 폴트당 디스크 I/O가 수 ms로 비싸, 폴트율을 낮추는 예측 규칙이 성능에 직결됨
- 목표: 미래 참조를 잘 근사해 폴트율을 Optimal에 가깝게, 구현 비용은 감당 가능하게 유지함

## Ⅱ. 구조 및 구성요소
선형 텍스트 구조도:
```
페이지 폴트 발생 & 빈 프레임 없음
  -> 교체 정책 호출
       -> FIFO: 적재 큐의 head 선택
       -> LRU: 최근 사용 시각 최소 페이지 선택
       -> Clock: 참조비트 0 만날 때까지 바늘 회전 / 1은 0으로 리셋
       -> Optimal: 다음 참조까지 거리 최대 페이지 선택(이론)
  -> victim 디스크 기록(dirty면) -> 새 페이지 적재 -> 테이블 갱신
```

| 구성요소 | 역할 | 비고 |
| --- | --- | --- |
| 교체 정책 | victim 선택 알고리즘 | FIFO/LRU/LFU/Clock/OPT |
| 참조비트 | Clock의 2차 기회 판단 | MMU가 세팅 |
| Dirty 비트 | 수정 여부, 기록 필요 판단 | 1이면 디스크 write |
| 프레임 큐/리스트 | 적재 순서·사용 이력 관리 | 알고리즘별 자료구조 |

> 요약: 폴트 시 정책이 victim을 고르고, dirty 페이지만 기록 후 새 페이지를 적재함.

## Ⅲ. 동작원리 및 흐름도
선형 텍스트 흐름도(Clock 예시):
```
폴트 -> 빈 프레임? -> 있음: 즉시 적재
                   -> 없음: 바늘 위치 페이지 참조비트 검사
바늘 페이지 -> 비트=1? -> 예: 비트=0 리셋 후 바늘 전진(2차 기회)
                       -> 아니오(비트=0): victim 선택 -> 교체
```
1. MMU가 폴트를 일으키면 OS가 빈 프레임을 찾고, 없으면 교체 정책을 호출함.
2. Clock은 바늘이 가리키는 페이지의 참조비트를 검사해 1이면 0으로 리셋하고 다음으로 전진함.
3. 참조비트 0인 페이지를 만나면 victim으로 확정하고, dirty면 디스크에 기록함.
4. victim 자리에 새 페이지를 적재하고 페이지 테이블·TLB를 갱신한 뒤 폴트 명령을 재실행함.

## Ⅳ. 특징
- FIFO — 구현이 큐 하나로 단순하나, 사용 빈도를 무시해 Belady 이상현상 위험이 있음
- LRU — 지역성 기반으로 폴트율이 낮으나, 매 참조 시각 기록·정렬 비용이 큼
- Clock(2차 기회) — 참조비트 1개로 LRU를 근사해 하드웨어 비용이 낮아 실무 표준임
- Optimal — 폴트율 이론적 하한이나 미래 참조열을 알아야 해 실측 불가, 성능 상한 기준으로만 사용함

## Ⅴ. 심화 비교 및 적용 판단
동일 참조열·프레임에서 폴트율과 구현 특성이 세 알고리즘에서 대비된다.

| 구분 | FIFO | LRU | Optimal |
| --- | --- | --- | --- |
| 선택 기준 | 적재가 가장 오래됨 | 참조가 가장 오래됨 | 미래 재참조가 가장 늦음 |
| 폴트율 | 높음(패턴 취약) | 낮음(지역성 활용) | 최저(이론 하한) |
| Belady 이상현상 | 발생 | 없음(스택 알고리즘) | 없음(스택 알고리즘) |
| 구현 비용 | 낮음 | 높음(시각 관리) | 불가(예측 필요) |
| 용도 | 단순 참고 | 근사 목표 | 성능 상한 기준 |

> 요약: Optimal은 도달 목표·상한, LRU는 실용 근사, FIFO는 Belady 위험으로 지양하며, 실무는 Clock으로 LRU를 값싸게 근사함.

- 리스크 — Belady 이상현상 — 원인: FIFO의 비스택 성질 — 대응: LRU·Clock 등 스택 알고리즘 채택
- 리스크 — LRU 관리 오버헤드 — 원인: 매 참조 시각 갱신 — 대응: 참조비트 기반 Clock 근사
- 지표 — 페이지 폴트율 — 목표: 워크로드별 임계 이하 — 측정: `/proc/vmstat`의 pgfault·pgmajfault 집계

## Ⅵ. 실무 적용 및 결론
- 적용 방안: 리눅스는 Active/Inactive LRU 리스트 + 참조비트 기반 재활용으로 Clock 계열을 확장 적용함
- 적용 방안: DB 버퍼 풀에서 LRU-K·2Q로 한 번 스캔되고 마는 페이지의 캐시 오염을 방지함
- 적용 방안: 알고리즘 검증 시 참조열 트레이스로 FIFO의 Belady 이상현상을 재현해 스택 알고리즘 필요성을 입증함
- 결론: 순차 대량 스캔이 잦으면 스캔 저항형(2Q·LRU-K), 일반 지역성 워크로드는 Clock 근사가 적합함
- 향후 방향: 접근 패턴 학습 기반 적응형 교체(ML 힌트)로 폴트율을 Optimal에 더 근접시킴
