## 미리 알고가기

- 페이지 교체는 메모리 부족 시 어떤 페이지를 내보낼지 결정하는 정책임
- page fault는 필요한 페이지가 메모리에 없을 때 발생함
- 목표는 fault를 줄이면서도 구현 비용과 오버헤드를 관리하는 것임

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 물리 메모리가 가득 찬 상태에서 새로운 페이지를 적재하기 위해 기존 페이지 중 어떤 것을 희생할지 결정하는 메모리 관리 정책임
- **배경/필요성**: 가상 메모리 시스템에서는 모든 페이지를 동시에 메모리에 둘 수 없으므로, 교체 정책이 page fault 빈도와 시스템 응답성과 디스크 I/O 규모를 직접 좌우함

## Ⅱ. 특징

- 미래 참조를 완벽히 알 수 없으므로 근사 정책이 주로 사용됨
- locality를 잘 반영할수록 page fault를 줄이기 쉬움
- 구현 복잡도와 하드웨어 지원 수준에 따라 적용 가능 정책이 달라짐
- 잘못된 정책은 스래싱을 유발해 CPU보다 I/O가 지배하는 상태를 만들 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | FIFO | LRU | LFU | OPT |
|:---|:---|:---|:---|:---|
| 기준 | 먼저 들어온 페이지 | 가장 오래 미사용 페이지 | 사용 빈도 낮은 페이지 | 미래에 가장 늦게 쓰일 페이지 |
| 장점 | 구현 단순 | locality 반영 우수 | 반복 참조 패턴 반영 | 이론적 최적 기준 |
| 한계 | Belady anomaly 가능 | 구현 비용 큼 | 초기 빈도 편향 가능 | 실제 구현 불가 |
| 활용 의미 | 단순 기준선 | 실무 근사 목표 | 특수 패턴 분석 | 비교용 상한선 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Frame Set | 실제 메모리에 적재된 페이지 집합으로 교체 후보 범위를 형성함 |
| Reference History | 최근 사용 시점이나 빈도 정보가 교체 정책 판단의 핵심 근거가 됨 |
| Victim Selector | 알고리즘 규칙에 따라 희생 페이지를 선택해 page fault 비용을 좌우함 |
| Fault Handler | 희생 페이지 제거와 신규 페이지 적재와 dirty page 기록을 수행함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 페이지 참조     | --> | 적중 여부 확인 | --> | 희생 페이지 선택 | --> | 교체 및 갱신   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **페이지 참조**: 프로세스가 특정 가상 페이지를 요구함
2. **적중 여부 확인**: 메모리에 있으면 참조 정보만 갱신함
3. **희생 페이지 선택**: page fault 시 정책에 따라 내보낼 페이지를 고름
4. **교체 및 갱신**: 신규 페이지를 적재하고 참조 이력을 갱신함

## Ⅵ. 문제점 및 해결 방안

1. 문제: locality를 잘 반영하지 못하는 정책은 page fault가 급증해 디스크 I/O 병목을 만들 수 있음
   - 해결방안: workload에 맞는 LRU 계열이나 working set 기반 정책을 적용하고 page fault rate와 disk wait time으로 검증함
2. 문제: 정확한 LRU 구현은 시간 정보 관리 비용이 커 커널 오버헤드를 증가시킬 수 있음
   - 해결방안: clock 같은 근사 알고리즘을 사용하고 replacement overhead와 fault reduction ratio로 검증함
3. 문제: 메모리 프레임 수를 무리하게 줄이면 좋은 정책도 스래싱 상태를 막지 못할 수 있음
   - 해결방안: 최소 resident set과 admission control을 적용하고 working set miss rate와 swap I/O rate로 검증함

## Ⅶ. 적용 사례

- 교육용 운영체제 실습에서는 FIFO와 LRU를 비교하고, page fault rate와 replacement overhead로 결과를 확인함
- 서버 커널 튜닝에서는 clock 계열 정책을 사용하고, disk wait time과 swap I/O rate로 결과를 확인함
- 메모리 과점유 환경에서는 working set 기반 제어를 도입하고, working set miss rate와 throughput stability로 결과를 확인함

## Ⅷ. 결론

페이지 교체 정책의 평가는 알고리즘 이름보다 locality 반영 정도와 구현 오버헤드와 스래싱 억제 효과를 함께 보는 것이 맞음.
