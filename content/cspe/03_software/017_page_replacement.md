## Ⅰ. 개요
- 정의: 페이지 폴트 발생 시 빈 프레임이 없으면 희생될 페이지를 결정하는 기법
- 배경: 한정된 물리 메모리 환경에서 페이지 교체 효율이 시스템 성능(I/O 부하)을 결정함
- 출제 의도: LRU, LFU, FIFO 등 주요 알고리즘의 동작 원리와 성능 특성 비교 역량 평가

## Ⅱ. 구성요소
```
[ Reference String ] 1 -> 2 -> 3 -> 4 -> 1 -> 2
[ Frames (3) ]
  FIFO: [1,2,3] -> [2,3,4] -> [3,4,1] -> [4,1,2] (Faults: 6)
  LRU : [1,2,3] -> [2,3,4] -> [3,4,1] -> [4,1,2] (Ref에 따라 다름)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| FIFO | 가장 먼저 들어온 페이지를 교체 | 선착순 퇴거 |
| LRU | 가장 오랫동안 사용되지 않은 페이지를 교체 | 구면 우선 퇴거 |
| LFU | 참조 횟수가 가장 적은 페이지를 교체 | 비인기 품목 퇴거 |
> 요약: 미래 예측이 불가능하므로 과거 이력을 바탕으로 희생자를 선택함.

## Ⅲ. 절차
```
[Fault] -> [Search Victim] -> [Write Back (if dirty)] -> [Swap In]
```
1. 페이지 폴트 발생 및 가용 프레임 부재 확인 시 알고리즘 수행
2. 선택된 정책(LRU 등)에 따라 교체 대상인 희생 페이지(Victim Page) 결정
3. 희생 페이지가 수정되었다면(Dirty bit=1) 디스크에 기록 후 해제
4. 새로운 페이지를 빈 프레임에 적재하고 페이지 테이블 정보 갱신
> 요약: 최적의 희생자를 찾아 교체함으로써 폴트 발생률을 최소화함.

## Ⅳ. 문제점
- 원인: FIFO에서 프레임이 늘어났는데 폴트가 증가하는 Belady의 모순 발생함
- 원인: LRU 구현을 위한 참조 시각 기록 및 탐색 오버헤드가 하드웨어적으로 부담됨

## Ⅴ. 개선방안
- (단기) 클럭(Clock) 알고리즘(NRU) 등 LRU 근사 알고리즘을 사용하여 하드웨어 부담 경감
- (중기) 페이지 버퍼링(Page Buffering) 도입으로 교체 결정 전 유예 기간 확보
- (장기) 애플리케이션의 메모리 참조 패턴을 학습하여 미리 불러오는 Prefetching 결합

## Ⅵ. 전망
- NVMe SSD 등 저장장치 속도 향상에 따라 교체 정책의 지연 시간 임계치가 변화하고 있음
- 머신러닝 기반의 적응형 페이지 교체 알고리즘이 특정 워크로드(DB, AI)에서 최적의 성능 발휘 예상
