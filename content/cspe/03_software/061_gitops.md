## 미리 알고가기

- GitOps는 Git 저장소를 운영 상태의 단일 진실 원천으로 삼는 운영 방식임
- 선언적 설정과 자동 동기화가 핵심임
- 변경 승인과 배포 추적성이 좋아지지만 drift 관리가 중요함

## Ⅰ. 개요

- **정의/개념**: GitOps는 인프라와 애플리케이션 배포 상태를 선언적 파일로 Git에 저장하고, 운영 환경이 그 저장소와 자동으로 동기화되도록 운용하는 배포·운영 방식임
- **배경/필요성**: 수동 설정 변경과 운영자 직접 배포는 추적성과 재현성이 낮아 장애와 보안 위험을 키우므로, Git 기반 승인 흐름으로 운영 상태를 관리할 필요가 커짐

## Ⅱ. 특징

- Git 커밋 이력이 운영 변경 이력이 되어 감사와 롤백이 쉬움
- 선언적 모델로 원하는 상태와 실제 상태 차이를 자동 감지함
- 배포 권한을 Git 승인 흐름으로 통제할 수 있음
- Git과 실제 환경의 drift를 어떻게 다루는지가 실무 핵심임

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 수동 운영 | GitOps |
|:---|:---|:---|
| 변경 출발점 | 운영자 직접 변경 | Git 변경 승인 |
| 추적성 | 제한적 | 커밋 기반 추적 용이 |
| 장점 | 즉시 조작 가능 | 재현성과 감사성 우수 |
| 한계 | drift와 실수 위험 큼 | 선언적 관리와 동기화 체계 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Desired State Repository | 운영에 필요한 선언적 설정을 보관해 단일 진실 원천 역할을 함 |
| Reconciliation Controller | 실제 환경과 Git 상태를 비교해 차이를 자동으로 맞춤 |
| Review and Approval Flow | 운영 변경을 코드 리뷰와 승인 절차로 관리해 권한 통제를 강화함 |
| Drift Detection | 수동 변경이나 실패로 생긴 불일치를 찾아 자동 복원이나 경보를 수행함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 설정 변경 커밋  | --> | 리뷰/승인      | --> | 자동 동기화    | --> | drift 감시      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **설정 변경 커밋**: 원하는 상태를 Git에 반영함
2. **리뷰 및 승인**: 정책에 따라 변경을 검토함
3. **자동 동기화**: 컨트롤러가 실제 환경을 원하는 상태로 맞춤
4. **drift 감시**: 불일치가 생기면 복원하거나 경보를 발송함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 운영자가 직접 환경을 수정하면 Git 상태와 실제 상태가 어긋나 재현성과 감사성이 무너질 수 있음
   - 해결방안: 직접 변경을 제한하고 drift detection을 운영하며 drift count와 manual change incident rate로 검증함
2. 문제: 선언 파일 구조가 복잡하면 작은 변경도 리뷰와 승인 비용이 과도해질 수 있음
   - 해결방안: 템플릿과 모듈화를 적용하고 review lead time과 config reuse rate로 검증함
3. 문제: Git 승인 흐름이 보안은 강화해도 긴급 장애 대응 속도를 늦출 수 있음
   - 해결방안: break-glass 절차를 정의하고 emergency recovery time과 audit completeness로 검증함

## Ⅶ. 적용 사례

- 쿠버네티스 운영 조직에서는 GitOps를 적용하고 확인 지표는 drift count와 deployment traceability score임
- 보안 민감 환경에서는 승인 흐름을 강화하고 확인 지표는 manual change incident rate와 audit completeness임
- 대규모 플랫폼 팀에서는 선언 템플릿을 표준화하고 확인 지표는 config reuse rate와 review lead time임

## Ⅷ. 결론

GitOps의 핵심은 Git을 쓰는 데 있지 않고 운영 상태를 선언형으로 통제해 수동 변경과 재현성 손실을 줄이는 데 있음.
