## 미리 알고가기

- 데이터 레지던시는 데이터가 저장·처리되는 물리적 위치를 제한함
- 법적·관할 주권은 서비스와 데이터가 적용받는 법률·외국 기관 요구·권리 집행 범위를 다룸
- 운영 주권은 정한 관할의 인력과 조직이 서비스 운영·지원·복구를 통제하는 능력임
- 기술 주권은 개방성·상호운용성·감사 가능성과 특정 공급자 종속 범위를 다룸
- 암호키 통제는 키 생성·보관·사용·폐기 권한과 운영자 접근 경계를 포함함
- 출구 전략은 데이터·이미지·설정·로그를 다른 환경으로 이전하고 기존 사본을 폐기하는 계획임

## 작성 근거(검토용)

- 소버린 클라우드는 위치를 넘어 법적 관할·데이터·운영·기술·키 통제를 핵심 축으로 설명함
- 비교표는 데이터 레지던시 중심 구성과 소버린 클라우드의 통제 범위 차이를 대비함
- 공공 업무 시스템과 규제 데이터 플랫폼에서 관할·키·운영·이전 증적을 검증함

## Ⅰ. 개요

- **정의/개념**: 소버린 클라우드는 정한 국가·지역의 법과 통제 주체가 데이터·암호키·운영·기술 의존성을 관리하도록 구성한 클라우드 환경임
- **배경/필요성**: 데이터 위치만으로 외국 관할권·원격 관리자·공급망·기술 종속 위험을 다룰 수 없어 주권 범위별 통제 기준이 필요함

## Ⅱ. 특징

- 데이터 저장·처리·백업·지원 과정의 지리적 경계와 이동 경로를 제한함
- 서비스 제공 법인·운영 인력의 관할과 외부 기관의 데이터 접근 가능성을 평가함
- 고객 또는 승인된 주체가 암호키와 관리자 접근을 관리하고 감사 증적을 보유함
- 운영 지속성·공급망·상호운용성·출구 가능성까지 주권 평가 범위에 포함함

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 레지던시 중심 | 소버린 클라우드 |
|:---|:---|:---|
| 핵심 범위 | 저장·처리 위치 제한 | 위치·관할·운영·기술·공급망 통제 |
| 법적 관할 | 지역 선택과 계약 조건 확인 | 제공 법인·외국 법 적용·권리 집행까지 평가 |
| 관리자 접근 | 접근 위치와 계정 정책 설정 | 승인 관할의 인력·조직·지원 경로로 제한 |
| 암호키 통제 | 지역 내 키 저장·사용 | 키 소유·사용 승인·복구·폐기 권한 통제 |
| 기술 의존 | 서비스 기능과 지역 가용성 중심 | 개방성·감사 가능성·이전 가능성 평가 |
| 검증 증적 | 저장 위치·복제 지역·전송 기록 | 관할·운영자·키·공급망·출구 시험 증적 |

> 요약: 소버린 클라우드는 데이터 위치뿐 아니라 법적 관할·운영자·키·기술 의존까지 통제함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 주권 요구사항 | 적용 법률·허용 지역·운영 주체·기술 독립 수준을 정의함 |
| 데이터 경계 | 저장·처리·복제·백업·지원 데이터의 이동 범위를 제한함 |
| 신원·관리 경계 | 관리자 위치·소속·권한·승인·비상 접근을 통제함 |
| 고객 통제 키 | 키 생성·보관·사용·회전·폐기와 제공자 접근 조건을 관리함 |
| 주권 운영 조직 | 관할 내 운영·지원·사고 대응·업데이트 책임을 수행함 |
| 감사·출구 체계 | 접근·변경·관할 증적과 데이터·워크로드 이전 시험을 제공함 |

```text
주권 요구사항 -> 데이터·관리·키 경계 -> 주권 운영 조직 -> 감사 증적
       |                                              |
       +--------------- 출구 전략·이전 시험 ----------+
```

> 요약: 주권 요구사항이 데이터·관리자·키·운영 경계로 구현되고 감사와 출구 시험으로 검증됨.

## Ⅵ. 실무 사례

1. 공공 업무 시스템은 관할 내 운영자·고객 키를 적용하고 관할 외 접근·미승인 키 사용 건수를 확인함
2. 규제 데이터 플랫폼은 지역 복제와 출구 시험을 수행하고 이전 시간·잔존 데이터 건수를 확인함

## Ⅶ. 결론

- 소버린 클라우드는 관할·운영·키·기술 독립 수준을 정하고 접근·이전 증적으로 검증해야 함
