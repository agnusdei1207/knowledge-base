# 📖 【암기용】 개념 완전 이해

> 목적: 소버린 클라우드를 처음 보는 사람도 데이터 주권, 운영 주권, 법적 관할권의 의미를 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 소버린 클라우드는 데이터와 운영 통제를 특정 국가·기관의 법적 관할 안에 두는 클라우드 모델이다.
- **왜 필요한가**: 공공·금융·국방 데이터는 해외 법령, 외국 사업자 접근, 국외 이전 리스크를 제한해야 한다.
- **핵심 직관**: 클라우드를 쓰되 데이터 금고의 위치, 열쇠 관리, 운영자 신분, 법원 관할을 국내 기준으로 묶는 방식이다.

## 깊이 이해
- **배경·문제의식**: 글로벌 클라우드는 리전 선택이 가능하지만 운영 권한, 지원 인력, 암호키, 메타데이터가 외국 법령 영향을 받을 수 있다.
- **작동 원리**: 데이터 저장 위치를 국내로 제한하고, 암호키를 고객 또는 국내 기관이 관리한다. 운영 인력, 접근 로그, 감사 기준, 법적 요청 절차를 주권 요구사항에 맞춘다.
- **비유**: 해외 은행 서비스를 쓰더라도 금고는 국내 지점에 두고, 열쇠는 본인이 보관하며, 분쟁은 국내 법으로 처리하는 구조이다.
- **구체 예시**: 공공 시스템은 데이터 국내 저장, 국내 운영자 접근, KMS/HSM 키 통제, 감사 로그 1년 이상 보존 같은 요건을 계약에 넣을 수 있다.
- **흔한 오해·주의점**: 소버린 클라우드는 단순 국내 리전 사용과 다르다. 운영 주체, 암호키, 지원 접근, 법적 관할까지 함께 검토해야 한다.

## 연결 개념
- 클라우드 배포 모델: Public, Private, Hybrid, Community Cloud와 비교
- 데이터 거버넌스: 데이터 분류, 국외 이전, 보존 정책
- Zero Trust: 운영자 접근과 관리자 권한 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 소버린 클라우드를 데이터 위치가 아니라 주권 요구사항과 클라우드 아키텍처 선택 기준으로 작성한다.
> 핵심: 출제자는 공공·금융 환경에서 규제 준수와 클라우드 탄력성의 트레이드오프를 보는 판단을 요구한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소버린 클라우드는 데이터, 암호키, 운영 접근, 법적 관할을 특정 국가 또는 기관의 통제 안에 두는 클라우드 모델이다.
> 2. **가치**: 공공·금융·의료 데이터의 국외 이전, 외국 법령 접근, 운영자 권한 남용 리스크를 계약과 기술 통제로 줄인다.
> 3. **판단 포인트**: 국내 리전만으로는 부족하며 데이터 분류, 키 관리, 관리자 접근, 감사 로그, 공급자 계약 조건을 함께 검토해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 주권 요구사항 이해 확인 | 데이터 위치, 법적 관할, 운영자 접근, 키 관리 | 국내 리전 사용만 설명 |
| 클라우드 아키텍처 선택 판단 확인 | Public, Private, Hybrid, Sovereign 비교 | 모든 업무를 소버린으로 이전한다고 단정 |
| 규제·감사 통제 확인 | 접근 로그, KMS/HSM, 계약 조항 | 기술 통제 없이 정책만 서술 |

> 요약: 소버린 클라우드 답안은 주권 요구사항을 기술·운영·계약 통제로 분해해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터 주권 보장 클라우드 모델
- 배경: 공공·금융·의료 시스템은 국외 이전과 외국 법령 접근 위험을 통제해야 한다.
- 필요성: 데이터 위치, 운영 주체, 암호키, 감사 로그를 주권 요구사항과 규제 기준에 맞춰 설계한다.

---

## Ⅱ. 구조 및 구성요소

```text
Data Classification -> Sovereign Region/Zone -> Customer Key/HSM
                                      +-> Local Operator -> Audit/Legal Control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 위치 통제 | 저장·백업 위치 제한 | 국내 리전, 국외 복제 금지 |
| 키 관리 | 암호키 소유와 접근 제한 | BYOK, HYOK, HSM |
| 운영 주권 | 관리자·지원 접근 통제 | 국내 인력, JIT 접근 |
| 법적·감사 통제 | 관할권과 로그 증적 | 감사 로그 1년 이상, 계약 조항 |

> 요약: 소버린 클라우드는 데이터 저장 위치보다 키, 운영자, 감사, 법적 통제를 함께 요구한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
업무 데이터 분류 -> 주권 요구사항 매핑 -> 배포 모델 선택
-> 암호키/접근 정책 적용 -> 로그 감사 -> 계약·규제 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 등급 분류 | 개인정보, 공공기록, 기밀 |
| 2 | 저장·처리 위치 결정 | 국내 저장 100% |
| 3 | 키와 접근 권한 설정 | 고객 관리 키, MFA 100% |
| 4 | 운영 접근 승인 | JIT, Break-glass 기록 |
| 5 | 감사와 보고 | 접근 로그, 규제 점검표 |

> 요약: 소버린 클라우드는 데이터 등급에서 시작해 위치, 키, 접근, 감사 기준을 순차적으로 확정한다.

## Ⅳ. 특징

| 구분 | 일반 퍼블릭 클라우드 | 소버린 클라우드 | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 위치 | 리전 선택 | 국외 이전 제한 | 저장·백업 위치 |
| 키 관리 | CSP 관리 KMS | BYOK/HYOK/HSM | 고객 통제 수준 |
| 운영 접근 | 글로벌 지원 조직 | 국내·인가 인력 제한 | 접근 로그와 승인 |
| 비용/운영 | 서비스 선택 폭 넓음 | 서비스 범위 제한 가능 | 규제 리스크 대비 |

> 요약: 소버린 클라우드는 서비스 선택 폭보다 데이터 주권과 감사 가능성을 우선하는 업무에 적합하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | Public Cloud | Sovereign Cloud | 국외 이전 제한 데이터 |
| 비용/성능 | 글로벌 리전·서비스 활용 | 국내 주권 구역과 제한 서비스 | 규제 위반 비용이 클 때 |
| 운영/위험 | CSP 표준 운영 | 고객 키·접근 승인 | 외국 법령 접근 우려 시 |

> 요약: 소버린 클라우드는 모든 워크로드가 아니라 주권 요구가 명확한 데이터와 업무에 선별 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 형식적 주권 | 국내 리전만 적용 | 키·운영·계약 요건 포함 | 주권 통제 체크리스트 |
| 서비스 제약 | 일부 관리형 서비스 미제공 | Hybrid 설계와 대체 서비스 | 서비스 적합성 비율 |
| 감사 실패 | 관리자 접근 기록 미흡 | JIT 접근, 세션 기록 | 접근 로그 누락 0건 |

> 요약: 소버린 클라우드 리스크는 국내 위치만으로 주권을 판단할 때 발생하므로 통제 항목을 계약과 로그로 검증해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 주권 | 국내 저장·백업 100% | CSP 리전 정책, DLP |
| 키 통제 | 고객 관리 키 100% | KMS/HSM 로그 |
| 운영 감사 | 관리자 접근 승인 100%, 로그 보존 1년 이상 | IAM, SIEM, 감사 보고서 |

> 요약: 소버린 클라우드는 데이터 위치, 키 소유, 운영 접근 기록을 정량 점검해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 등급을 공공기록, 개인정보, 일반 데이터로 분류하고 공공기록·민감정보는 국내 저장과 국외 복제 금지 정책을 적용함
2. BYOK/HYOK와 HSM을 적용해 키 생성·폐기·회전 권한을 고객 또는 국내 기관에 두고 키 접근 로그를 SIEM에 저장함
3. 운영자 접근은 MFA, JIT 승인, 세션 기록, Break-glass 사후 승인으로 통제하고 계약에 법적 관할과 지원 접근 조건을 명시함

**결론 (2줄):**
- 기술사 판단: 규제 민감 데이터는 소버린 클라우드를 적용하고, 일반 웹·분석 업무는 퍼블릭 또는 하이브리드로 비용과 기능 범위를 조정함
- 향후 방향: 국가별 데이터 규제와 산업별 클라우드 인증이 확대되며 주권 요구사항은 계약, 키 관리, 운영 감사 중심으로 세분화됨
