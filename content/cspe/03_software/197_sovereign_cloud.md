# 📖 【암기용】 개념 완전 이해

> 목적: 소버린 클라우드를 처음 보는 사람도 데이터 주권·운영 주권·법적 관할권이 왜 국내 리전 사용만으로는 해결되지 않는지 완전히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 소버린 클라우드는 **데이터 주권(Data Sovereignty)**과 **운영 주권(Operational Sovereignty)**을 특정 국가·기관의 **법적 관할권(Jurisdiction)** 안에 두는 클라우드 배포 모델이다.
- **왜 필요한가**: 공공·금융·국방 데이터는 해외 법령에 의한 강제 접근, 외국 사업자의 운영 접근, 데이터의 국외 이전 리스크를 제한해야 한다.
- **핵심 직관**: 클라우드를 쓰되 데이터 금고의 위치, 열쇠 관리자, 운영자 신분, 분쟁 시 재판 관할을 국내 기준으로 묶는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 데이터 주권 (Data Sovereignty) | 데이터가 저장·처리되는 국가의 법을 따른다는 원칙 — 소버린 클라우드가 지키려는 **핵심 목표** | 내 물건은 내 나라 법의 보호를 받는다 |
| 운영 주권 (Operational Sovereignty) | 데이터에 접근·운영하는 인력·절차까지 국내 통제 아래 두는 것 | 금고 관리인도 내국인이어야 한다 |
| 법적 관할권 (Jurisdiction) | 분쟁·수사·강제 접근 시 어느 나라 법원·법령이 적용되는가 | 사건이 나면 어느 나라 법정으로 가는가 |
| BYOK (Bring Your Own Key) | 고객이 암호키를 생성해 클라우드 KMS에 등록해 사용 | 자물쇠는 CSP 것, 열쇠는 내 것 |
| HYOK (Hold Your Own Key) | 암호키를 CSP에 넘기지 않고 고객·국내 기관이 직접 보관 | 열쇠를 아예 남에게 맡기지 않음 |
| HSM (하드웨어 보안 모듈) | 암호키를 물리적으로 안전하게 저장·연산하는 전용 장치 | 은행 금고 속 금고 |
| JIT 접근 (Just-In-Time) | 필요한 순간에만 임시로 접근 권한을 부여하는 방식 | 방문 시간만 유효한 출입증 |
| Break-glass | 긴급 상황에서 절차를 건너뛰고 접근하되 사후 감사하는 예외 절차 | 비상시에만 깨는 유리함 |

## 깊이 이해

### 왜 국내 리전만으로는 부족한가 (배경 — CLOUD Act 사례로 이해)
- 글로벌 CSP는 국내 리전을 제공해도, 그 CSP의 본사가 있는 국가의 법이 리전 위치와 무관하게 적용될 수 있다. 대표적으로 미국의 CLOUD Act(2018)는 미국 기업이 해외 리전에 저장한 데이터라도 미국 정부의 요청에 따라 제출하도록 강제할 수 있는 근거를 담고 있다.
- 즉 "데이터가 국내 리전에 저장되어 있다"는 사실만으로는 외국 법령의 강제 접근을 막지 못한다. 그래서 소버린 클라우드는 저장 위치뿐 아니라 운영 주체(어느 나라 회사·인력이 관리하는가)와 암호키 소유까지 함께 통제한다.

### BYOK와 HYOK — 무엇이 다른가
- BYOK는 고객이 키를 만들어 CSP의 KMS에 등록하지만, 실제 암·복호화 연산은 여전히 CSP 인프라 안에서 일어난다. CSP가 마음만 먹으면(또는 법적으로 강제되면) 키에 접근할 여지가 남는다.
- HYOK는 키를 CSP에 아예 넘기지 않고 고객 또는 국내 기관이 별도 HSM에서 직접 관리한다. 데이터를 암·복호화할 때마다 외부(국내) HSM에 요청을 보내는 구조라, CSP가 키 자체를 확보할 수 없다. 보안 수준은 HYOK가 더 높지만, 매 요청마다 외부 HSM을 호출해야 하므로 지연시간과 가용성 설계 부담이 커진다.

### 운영 주권 — 접근 통제를 수치로 이해
- "국내 인력만 운영 접근 가능"을 지키려면, 전 세계 어디서든 대응하는 글로벌 CSP의 표준 지원 조직과 다른 예외 계약이 필요하다. 예: 관리자 접근은 JIT로 세션당 최대 30분만 부여하고, 모든 세션은 녹화·로그로 남겨 감사 로그를 1년 이상 보존한다.
- Break-glass는 장애 대응처럼 즉시 접근이 필요한 예외 상황에서 절차를 생략하되, 사후에 반드시 승인·감사를 거치게 하는 안전판이다. 이것이 없으면 "국내 인력만 접근"이라는 원칙이 장애 상황에서 무너진다.

### 소버린 클라우드가 아닌 것 — 흔한 오해
- 단순히 "국내 리전을 선택했다"는 것은 소버린 클라우드가 아니다. 데이터 위치, 암호키 소유(BYOK/HYOK), 운영 인력의 국적과 접근 통제, 법적 관할까지 네 가지가 함께 충족되어야 한다. 하나라도 빠지면 "형식적 주권"에 그친다.

### 비유
- 해외 은행 서비스를 이용하더라도 금고는 국내 지점에 두고, 열쇠는 본인이 직접 보관하며, 분쟁이 생기면 국내 법으로 처리하는 구조와 같다. 은행(CSP)은 편의를 제공하지만, 최종 통제권은 고객·국내 기관에 남는다.

## 연결 개념
- 클라우드 배포 모델: Public, Private, Hybrid, Community Cloud와 비교
- 데이터 거버넌스: 데이터 분류, 국외 이전, 보존 정책
- Zero Trust: 운영자 접근과 관리자 권한 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 소버린 클라우드를 데이터 위치가 아니라 주권 요구사항과 클라우드 아키텍처 선택 기준으로 작성한다.
> 핵심: 출제자는 공공·금융 환경에서 규제 준수와 클라우드 탄력성의 트레이드오프를 보는 판단을 요구한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소버린 클라우드는 데이터, 암호키, 운영 접근, 법적 관할을 특정 국가 또는 기관의 통제 안에 두는 클라우드 모델이다.
> 2. **가치**: 공공·금융·의료 데이터의 국외 이전, 외국 법령 접근, 운영자 권한 남용 리스크를 계약과 기술 통제로 줄인다.
> 3. **판단 포인트**: 국내 리전만으로는 부족하며 데이터 분류, 키 관리, 관리자 접근, 감사 로그, 공급자 계약 조건을 함께 검토해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 주권 요구사항 이해 확인 | 데이터 위치, 법적 관할, 운영자 접근, 키 관리 | 국내 리전 사용만 설명 |
| 클라우드 아키텍처 선택 판단 확인 | Public, Private, Hybrid, Sovereign 비교 | 모든 업무를 소버린으로 이전한다고 단정 |
| 규제·감사 통제 확인 | 접근 로그, KMS/HSM, 계약 조항 | 기술 통제 없이 정책만 서술 |

> 요약: 소버린 클라우드 답안은 주권 요구사항을 기술·운영·계약 통제로 분해해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 데이터 주권 보장 클라우드 모델
- 배경: 공공·금융·의료 시스템은 국외 이전과 외국 법령 접근 위험을 통제해야 한다.
- 필요성: 데이터 위치, 운영 주체, 암호키, 감사 로그를 주권 요구사항과 규제 기준에 맞춰 설계한다.

## Ⅱ. 구조 및 구성요소

```text
Data Classification -> Sovereign Region/Zone -> Customer Key/HSM
                                      +-> Local Operator -> Audit/Legal Control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 위치 통제 | 저장·백업 위치 제한 | 국내 리전, 국외 복제 금지 |
| 키 관리 | 암호키 소유와 접근 제한 | BYOK, HYOK, HSM |
| 운영 주권 | 관리자·지원 접근 통제 | 국내 인력, JIT 접근 |
| 법적·감사 통제 | 관할권과 로그 증적 | 감사 로그 1년 이상, 계약 조항 |

> 요약: 소버린 클라우드는 데이터 저장 위치보다 키, 운영자, 감사, 법적 통제를 함께 요구한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
업무 데이터 분류 -> 주권 요구사항 매핑 -> 배포 모델 선택
-> 암호키/접근 정책 적용 -> 로그 감사 -> 계약·규제 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 등급 분류 | 개인정보, 공공기록, 기밀 |
| 2 | 저장·처리 위치 결정 | 국내 저장 100% |
| 3 | 키와 접근 권한 설정 | 고객 관리 키, MFA 100% |
| 4 | 운영 접근 승인 | JIT, Break-glass 기록 |
| 5 | 감사와 보고 | 접근 로그, 규제 점검표 |

> 요약: 소버린 클라우드는 데이터 등급에서 시작해 위치, 키, 접근, 감사 기준을 순차적으로 확정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 등급을 공공기록, 개인정보, 일반 데이터로 분류하고 공공기록·민감정보는 국내 저장과 국외 복제 금지 정책을 적용함
2. BYOK/HYOK와 HSM을 적용해 키 생성·폐기·회전 권한을 고객 또는 국내 기관에 두고 키 접근 로그를 SIEM에 저장함
3. 운영자 접근은 MFA, JIT 승인, 세션 기록, Break-glass 사후 승인으로 통제하고 계약에 법적 관할과 지원 접근 조건을 명시함

**결론 (2줄):**
- 기술사 판단: 규제 민감 데이터는 소버린 클라우드를 적용하고, 일반 웹·분석 업무는 퍼블릭 또는 하이브리드로 비용과 기능 범위를 조정함
- 향후 방향: 국가별 데이터 규제와 산업별 클라우드 인증이 확대되며 주권 요구사항은 계약, 키 관리, 운영 감사 중심으로 세분화됨
