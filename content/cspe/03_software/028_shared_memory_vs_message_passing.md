## Ⅰ. 개요
- 정의: 직접 메모리 영역을 공유하여 통신하는 방식과 커널을 통해 메시지를 주고받는 방식
- 배경: 데이터 크기, 통신 빈도, 구현 복잡도에 따른 최적의 IPC 모델 선택 필요
- 출제 의도: 두 방식의 성능적 특징(Speed vs Overhead) 및 신뢰성 측면의 장단점 비교

## Ⅱ. 구성요소
```
[ Shared Memory ]              [ Message Passing ]
+----------+----------+        +----------+----------+
| Process A| Process B|        | Process A| Process B|
+----------+----------+        +----------+----------+
|  Shared Region      |        | Kernel / Queue      |
+---------------------+        +---------------------+
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 공유 메모리 | 커널의 개입 없이 메모리 직접 읽기/쓰기 수행 | 한 책상에서 작업 |
| 메시지 패싱 | send/receive 시스템 호출을 통해 데이터 전송 | 메모 전달 |
| 동기화 도구 | 공유 메모리의 경합 방지를 위한 추가적인 기법 | 회의 규칙 |
> 요약: 공유 메모리는 최고 속도를, 메시지 패싱은 충돌 없는 안정성을 제공함.

## Ⅲ. 절차
```
[Setup] -> [Access] -> [Cleanup] (Shared Memory)
[Send] -> [Kernel Copy] -> [Receive] (Message Passing)
```
1. (공유) 커널에 메모리 세그먼트 요청 후 각 프로세스의 주소 공간에 맵핑(Attach)
2. (공유) 프로세스들이 직접 해당 주소에 데이터 쓰기/읽기 수행 (동기화 필수)
3. (패싱) 송신 측이 데이터를 커널 버퍼로 복사(Copy-in)하고 수신 측에 통지
4. (패싱) 수신 측이 커널 버퍼의 데이터를 자신의 공간으로 복사(Copy-out)하여 수신
> 요약: 커널을 경유하는지, 아니면 주소 공간을 합치는지의 절차적 차이가 있음.

## Ⅳ. 문제점
- 원인: 공유 메모리는 별도의 동기화 로직 구현 부담이 크며, 보안 취약점 발생 가능
- 원인: 메시지 패싱은 두 번의 메모리 복사 발생으로 대용량 데이터 전송 시 느려짐

## Ⅴ. 개선방안
- (단기) 메시지 패싱 성능 향상을 위해 커널 버퍼와 사용자 공간을 맵핑하는 가상 공유 방식 도입
- (중기) 공유 메모리 사용 시 검증된 라이브러리(Boost.Interprocess 등)를 활용하여 안정성 확보
- (장기) 불변 메시지(Immutable Message) 기반의 패싱 모델로 동기화 오버헤드 원천 차단

## Ⅵ. 전망
- 멀티코어 환경에서 코어 간 캐시 일관성 유지를 고려한 고성능 공유 메모리 기술 부각
- 고신뢰 시스템(Erlang 등)에서는 상태 공유를 지양하고 메시지 패싱만 사용하는 추세 강화
