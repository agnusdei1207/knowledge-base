## 미리 알고가기

- 선점형: 실행 중인 프로세스의 CPU 사용권을 회수할 수 있는 스케줄링 방식임
- CPU 버스트: 프로세스가 I/O 대기 없이 CPU를 연속 사용하는 시간임
- 반환시간·응답시간: 도착부터 완료까지의 시간과 도착부터 첫 실행까지의 시간임

## 작성 근거(검토용)

- FCFS·SJF·RR·MLFQ·CFS를 선택 기준·선점·얻는 결과·제약·적용 업무로 비교함
- 공통 실행 흐름은 준비 큐 삽입·정책 선택·선점·완료 상태 전이로 설명함
- 서버 사례는 RR의 시간 할당량과 CFS의 가중 CPU 배분을 직접 검증하도록 구성함

## Ⅰ. 개요
- **정의/개념**: 프로세스 스케줄링은 준비 큐에서 다음 실행 프로세스와 CPU 사용시간을 결정하는 운영체제 정책임
- **배경/필요성**: 작업별 CPU 버스트와 응답시간 요구가 다르므로 실행 순서와 선점 기준이 필요함

## Ⅱ. 특징

- 스케줄러는 준비 큐에서 정책 기준을 만족하는 프로세스를 선택함
- 선점 정책과 시간 할당량은 응답시간과 문맥 전환 횟수를 결정함
- CPU 버스트 예측과 우선순위 갱신 정확도가 SJF·MLFQ의 실행 순서에 영향을 줌
- 처리량·응답시간·공정성 요구에 따라 정책을 선택함

## Ⅲ. 종류 및 비교

| 판단 기준 | FCFS | SJF | RR | MLFQ | CFS |
|:---|:---|:---|:---|:---|:---|
| 선택 기준 | 도착 순서 | 예상 CPU 버스트 | 준비 큐 순서·시간 할당량 | 실행 이력·큐 우선순위 | 가중 가상 실행시간 |
| 선점 여부 | 비선점 | 비선점·선점 변형 | 선점 | 선점 | 선점 |
| 얻는 결과 | 도착 순서 유지 | 평균 대기시간 감소 | 첫 응답 기회 분산 | 대화형 작업 우선 처리 | CPU 사용량 편차 조정 |
| 주요 제약 | 호위 효과 | 버스트 예측·기아 | 시간 할당량별 전환 비용 | 큐·상향 주기 설정 | 가중치·최소 실행시간 설정 |
| 대표 적용 사례 | 배치 큐 | 실행시간 예측 가능 작업 | 시분할·대화형 시스템 | 혼합 워크로드 | 리눅스 범용 스케줄링 |

> 요약: FCFS는 도착 순서, SJF는 예상 버스트, RR은 시간 할당량, MLFQ는 실행 이력, CFS는 가상 실행시간으로 대상을 선택함.

## Ⅳ. 구성요소 및 구조
```
[Ready Queue] -> [ Scheduler ] -> [ CPU ]
  P3 P2 P1         (Algorithm)
```
| 구성요소 | 설명 | 선택 기준 |
| :--- | :--- | :--- |
| 준비 큐 | 실행 가능한 프로세스를 보관함 | 선택 후보 |
| 스케줄러 | 정책별 기준으로 다음 실행 대상을 선택함 | 실행 순서 |
| 디스패처 | 선택한 프로세스의 문맥을 복원해 CPU 제어권을 넘김 | 전환시간 |
| 타이머 | 시간 할당량 만료를 통지해 선점을 발생시킴 | 선점 시점 |
> 요약: 준비 큐·스케줄러·디스패처·타이머가 실행 대상과 선점 시점을 결정함.

## Ⅴ. 원리 및 절차 흐름도
```
[Arrival] -> [Queue Insert] -> [Pick by Policy] -> [Execution] -> [Completion]
```
1. **준비 큐 삽입**: 도착하거나 선점된 프로세스를 준비 큐에 넣음
2. **정책별 선택**: 도착 순서·버스트·시간 할당량·실행 이력·가상 실행시간으로 대상을 고름
3. **실행·선점**: 디스패치 후 완료·대기·시간 할당량 만료 상태를 판정함
4. **완료·재등록**: 완료하면 자원을 회수하고 선점되면 준비 큐에 다시 등록함
> 요약: 준비 큐에서 정책별 기준으로 대상을 선택하고 실행 결과에 따라 완료·대기·재등록 상태로 전환함.

## Ⅵ. 실무 사례

1. 대화형 운영체제는 RR 시간 할당량을 조정하고 첫 응답시간과 문맥 전환율을 확인함
2. 리눅스 서버는 CFS 가중치를 설정하고 태스크별 CPU 사용 편차와 스케줄링 지연을 확인함

## Ⅶ. 결론

- 프로세스 스케줄링은 CPU 버스트·응답시간·공정성 요구에 따라 선택 기준과 선점 정책을 정함
