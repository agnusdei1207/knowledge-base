## Ⅰ. 개요
- **정의**: Ready Queue의 프로세스 중 다음 CPU를 할당받을 대상을 선택하는 정책임
- **배경/필요성**: 한정된 CPU를 다수 프로세스가 경쟁하므로 공정성·응답성·처리량을 균형 잡는 기준이 필요함
- **비유**: 놀이공원에서 다음 탑승자를 정하는 대기열 운영 규칙과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 비선점/선점 알고리즘 비교 | 평가 지표(응답시간, 대기시간, 처리량, 반환시간) | 선점형에서 컨텍스트 스위칭 비용(002 참조)을 고려할 것 |

> 요약: 스케줄링은 CPU 활용과 사용자 응답성 사이의 최적점을 찾는 정책임

## Ⅱ. 구성요소
```text
+------------+    dispatch    +---------+
| Ready Queue| ------------> | CPU     |
+------------+    <---------- +---------+
       ^          preempt/        |
       |          timeout         | I/O request
       +--- I/O done ---  Wait Queue  <--+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 비선점 알고리즘 | 실행 중인 프로세스가 자발적으로 CPU를 반납할 때까지 대기함 (FCFS, SJF) | 한 명이 끝날 때까지 기다리는 창구 |
| 선점 알고리즘 | 우선순위가 높은 프로세스가 도착하면 현재 실행을 중단하고 교체함 (RR, SRTF) | 응급 환자가 오면 순서를 양보하는 응급실 |
| 스케줄링 평가 지표 | 응답시간, 대기시간, 반환시간, CPU 이용률, 처리량으로 성능을 측정함 | 놀이공원 만족도 지표 |

> 요약: 비선점/선점 방식을 평가 지표 기준으로 비교·선택함

## Ⅲ. 절차
```text
프로세스 도착 --> Ready Queue 삽입 --> 스케줄러 정책 적용 --> CPU 할당
```
- 1단계: 프로세스가 생성 또는 I/O 완료 후 Ready Queue에 삽입됨
- 2단계: 스케줄러가 정책(FCFS, SJF, RR 등)에 따라 다음 실행 대상을 선택함
- 3단계: 선택된 프로세스에 CPU를 할당하고 컨텍스트 스위칭(002 참조)을 수행함
- 4단계: 타임아웃·I/O 요청·종료 시 CPU를 회수하고 Ready/Wait/Terminated로 전이함

> 요약: 삽입-선택-할당-회수의 반복 사이클로 CPU를 배분함

## Ⅳ. 문제점
- FCFS 호위 효과: 긴 프로세스 뒤에 짧은 프로세스가 대기 — 평균 대기시간이 급증함
- SJF 기아 현상: 짧은 작업이 계속 도착하면 긴 작업이 무한 대기함 — 공정성이 훼손됨
- RR 슬라이스 딜레마: 슬라이스가 너무 짧으면 전환 비용 과다, 너무 길면 FCFS와 동일해짐

> 요약: 단순 알고리즘은 호위 효과, 기아, 슬라이스 설정 문제를 가짐

## Ⅴ. 개선방안
1. 단기: SJF에 에이징을 적용하여 대기 시간 증가 시 우선순위를 상향함
2. 중기: 다단계 피드백 큐(005 참조)로 작업 특성에 따라 큐를 분리·조정함
3. 장기: CFS(006 참조) 등 공정 스케줄러를 도입하여 가상 런타임 기반 공정 배분을 구현함

> 요약: 에이징, 다단계 큐, 공정 스케줄러로 단순 알고리즘의 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 에너지 효율 스케줄링(EAS)과 AI 기반 동적 정책 조정이 연구됨
- 기술사적 판단: 이기종 코어(big.LITTLE) 확산으로 코어 특성별 차등 스케줄링이 표준화됨
- 기술사 제언: 워크로드 프로파일링과 스케줄링 정책을 연동한 자동 튜닝 체계 구축이 필요
