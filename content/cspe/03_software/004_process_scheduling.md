# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: OS가 준비 큐(Ready Queue)에 대기 중인 프로세스들 중 **다음에 CPU를 할당받을 대상을 결정**하는 전략.
- **핵심 직관**: 한정된 창구(CPU)를 이용하려는 고객(프로세스)들에게 번호표를 나눠주고 부르는 규칙. (먼저 온 순서대로? 짧은 사람 먼저? 중요도가 높은 사람 먼저?)
- **목표 (The Goal)**: 
    - **CPU 이용률(Utilization)**: CPU가 놀지 않게 함.
    - **처리량(Throughput)**: 단위 시간당 끝내는 작업 수 극대화.
    - **반환 시간(Turnaround Time)**: 시작부터 종료까지의 시간 최소화.
    - **응답 시간(Response Time)**: 처음 CPU를 잡기까지의 시간 최소화.

## 깊이 이해
- **비선점(Non-preemptive) vs 선점(Preemptive)**:
    - **비선점**: 한 번 CPU를 잡으면 스스로 끝내거나 I/O를 하러 갈 때까지 뺏기지 않음. (예: FCFS, SJF)
    - **선점**: OS가 강제로 CPU를 뺏어 다른 프로세스에게 줄 수 있음. 시분할 시스템의 핵심. (예: Round Robin, MLFQ)
- **주요 알고리즘의 민낯**:
    - **FCFS (First-Come, First-Served)**: 선착순. 긴 작업이 앞에 오면 뒤가 다 밀리는 '호위 효과(Convoy Effect)' 발생.
    - **SJF (Shortest Job First)**: 짧은 것 먼저. 평균 대기시간 최적이지만, 긴 작업이 굶어 죽는 '기아(Starvation)' 발생.
    - **RR (Round Robin)**: 동일 시간(Time Quantum)씩 돌아가며 실행. 현대 시분할 시스템의 기본.
    - **Priority Scheduling**: 우선순위 부여. 낮은 순위는 영구 대기 가능 -> '에이징(Aging)' 기법으로 해결.

## 연결 개념
- **MLFQ (005)**: RR과 우선순위를 결합한 피드백 방식.
- **CFS (006)**: 리눅스 커널의 표준, '공정함'을 수치로 계산.
- **기아와 에이징 (011)**: 스케줄링의 고질병과 그 해법.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 한정된 CPU 자원을 다수의 프로세스에게 분배하여 시스템의 **처리량(Throughput)**과 **응답성(Responsiveness)** 사이의 균형을 맞추는 최적화 과정임.
> 2. **기술적 핵심**: 선점형 스케줄링은 잦은 문맥 전환(Context Switch) 오버헤드를 발생시키므로, 적정 **Time Quantum(시간 할당량)** 설정이 성능의 핵심임.
> 3. **진화**: 단순 우선순위 방식에서 프로세스의 행동 패턴(CPU/IO Bound)을 스스로 학습하여 적응하는 **MLFQ**와 공평성을 수치화한 **CFS**로 발전함.

## Ⅰ. 시스템 성능의 결정자, 프로세스 스케줄링 개요
- **정의**: 준비 큐에 있는 프로세스 중 어떤 프로세스에게 CPU를 할당할지 결정하는 커널의 핵심 기능.
- **필요성**: CPU 이용률 향상, 사용자 체감 응답성 개선, 시스템 처리 효율 극대화.

## Ⅱ. 스케줄링의 두 가지 큰 줄기: 비선점 vs 선점

| 구분 | 비선점 (Non-preemptive) | 선점 (Preemptive) |
|:---:|:---|:---|
| **제어권** | 프로세스가 자발적으로 반납 | OS가 강제로 회수 가능 |
| **특징** | 문맥 전환 오버헤드 적음, 공정성 낮음 | 대화형 시스템에 적합, 오버헤드 존재 |
| **알고리즘** | FCFS, SJF, HRN | Round Robin, SRT, MLFQ, CFS |
| **응답성** | 예측 가능하나 응답성 떨어짐 | 빠른 응답성 보장 |

## Ⅲ. 주요 스케줄링 알고리즘 상세 분석

### 1. FCFS (First-Come First-Served)
- **원리**: 큐에 도착한 순서대로 CPU 할당.
- **단점**: **호위 효과(Convoy Effect)**. 긴 프로세스 하나가 짧은 프로세스들의 대기 시간을 폭발적으로 증가시킴.

### 2. SJF (Shortest Job First)
- **원리**: CPU 버스트 시간이 짧은 프로세스에게 우선 할당.
- **가치**: 평균 대기 시간(Average Waiting Time)을 최소화하는 **최적 알고리즘**.
- **한계**: 다음 CPU 버스트 시간을 정확히 예측하기 어려움, 긴 작업의 **기아(Starvation)** 현상.

### 3. Round Robin (RR)
- **원리**: 각 프로세스에게 동일한 시간 할당량(Time Quantum)을 부여하고 순환.
- **핵심 파라미터**: 
    - **Quantum이 너무 크면**: FCFS와 동일해짐.
    - **Quantum이 너무 작으면**: 문맥 전환 오버헤드가 CPU 실행 시간보다 커짐.

### 4. HRN (Highest Response-ratio Next)
- **원리**: SJF의 기아 문제를 해결하기 위해 '우선순위 = (대기시간 + 서비스시간) / 서비스시간' 공식 사용.
- **효과**: 대기 시간이 길어질수록 우선순위가 높아지는 **에이징(Aging)** 효과 내장.

## Ⅳ. 스케줄링 알고리즘 비교 (종합)

| 알고리즘 | 선점여부 | 주요 평가 지표 | 특징 및 한계 |
|:---:|:---:|:---:|:---|
| **FCFS** | 비선점 | 대기 시간 | 호위 효과 발생 |
| **SJF** | 비선점 | 대기 시간 | 평균 대기 시간 최소, 기아 현상 |
| **SRT** | 선점 | 대기 시간 | 남은 시간이 짧은 순, SJF의 선점 버전 |
| **RR** | 선점 | 응답 시간 | 대화형 시스템 적합, Quantum 크기가 관건 |
| **Priority** | 선점/비선점 | 우선순위 | 긴급한 작업 처리, 기아 현상(Aging으로 해결) |

## Ⅴ. 스케줄링 성능 평가 척도 (Gantt Chart 활용의 근거)

- **CPU Utilization**: 전체 시간 중 CPU가 일한 시간의 비율 (Max 목표).
- **Throughput**: 단위 시간당 완료된 프로세스 개수 (Max 목표).
- **Turnaround Time**: 프로세스 제출부터 완료까지 걸린 시간 (Min 목표).
- **Waiting Time**: 준비 큐에서 기다린 총 시간 (Min 목표).
- **Response Time**: 요청 후 첫 번째 응답이 나올 때까지의 시간 (Min 목표).

## Ⅵ. 기술사 관점의 결론 및 제언
- 현대 OS는 단일 알고리즘이 아닌, **다단계 피드백 큐(MLFQ)**나 **CFS** 같은 복합 알고리즘을 사용함.
- **실무 제언**: 고부하 시스템 운영 시 스케줄링 정책을 직접 수정하기보다는, 프로세스의 **Nice값(우선순위 가중치)** 조정이나 **CPU Affinity(특정 코어 고정)** 설정을 통해 캐시 적중률을 높이고 문맥 전환 오버헤드를 통제하는 것이 더 효과적임.
