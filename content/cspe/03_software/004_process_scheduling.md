## Ⅰ. 개요
- 정의: CPU 이용률을 극대화하기 위해 준비 큐의 프로세스를 선택하는 기법
- 배경: 다중 프로그래밍 환경에서 공정성, 효율성, 응답 시간 최적화 필요
- 출제 의도: 주요 알고리즘별 특징, 장단점 및 대기/반환 시간 계산 능력 검증

## Ⅱ. 구성요소
```
[Ready Queue] -> [ Scheduler ] -> [ CPU ]
  P3 P2 P1         (Algorithm)
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| FIFO | 도착 순서대로 처리하는 비선점 방식 | 은행 번호표 |
| SJF | 실행 시간이 짧은 것부터 처리 (Convoy 방지) | 짧은 업무 우선 |
| RR | 정해진 시간(Quantum)씩 교대로 처리하는 선점 방식 | 이어달리기 |
> 요약: 스케줄러는 정책에 따라 다음에 실행할 최적의 프로세스를 결정함.

## Ⅲ. 절차
```
[Arrival] -> [Queue Insert] -> [Pick by Policy] -> [Execution] -> [Completion]
```
1. 프로세스가 시스템에 도착하면 Ready Queue의 후미에 삽입됨
2. 선택된 알고리즘(FIFO, SJF, RR 등)에 따라 실행할 프로세스를 추출함
3. 선점형(RR 등)의 경우 Time Slice 만료 시 다시 큐로 복귀함
4. 실행 완료 시 프로세스 반환 시간(Turnaround Time) 산출 및 자원 회수
> 요약: 대기 시간을 최소화하고 처리량을 극대화하는 방향으로 동작함.

## Ⅳ. 문제점
- 원인: FIFO에서 긴 프로세스가 앞에 있을 때 발생하는 호위 효과(Convoy Effect)
- 원인: SJF에서 긴 프로세스가 무한정 대기하는 기아(Starvation) 현상 발생함

## Ⅴ. 개선방안
- (단기) RR의 타임 퀀텀을 시스템 특성에 맞춰 최적화하여 응답성 확보
- (중기) 에이징(Aging) 기법을 도입하여 오래 대기한 프로세스 우선순위 상향
- (장기) 다단계 피드백 큐(MLFQ) 등 복합 스케줄링 모델로 전환하여 유연성 증대

## Ⅵ. 전망
- 클라우드 워크로드의 가변성에 대응하는 머신러닝 기반 동적 스케줄링 기술이 부각됨
- 에너지 효율적(Green IT)인 CPU 활용을 위해 전력 소모를 고려한 스케줄링 정책 강화 추세임
