## Ⅰ. 개요
- 정의: 준비 큐의 프로세스 중 다음에 CPU를 받을 대상을 정하는 운영체제 정책
- 배경: 작업 특성에 따라 대기 시간, 응답 시간, 처리량이 달라지므로 선택 기준이 필요함
- 출제 의도: 주요 알고리즘별 특징, 장단점 및 대기/반환 시간 계산 능력 검증

## Ⅱ. 구성요소
```
[Ready Queue] -> [ Scheduler ] -> [ CPU ]
  P3 P2 P1         (Algorithm)
```
| 구성요소 | 설명 | 선택 기준 |
| :--- | :--- | :--- |
| FIFO | 도착 순서대로 처리하는 비선점 방식 | 도착 시간 |
| SJF | 실행 시간이 짧은 것부터 처리 | 예상 CPU burst |
| RR | 정해진 시간(Quantum)씩 교대로 처리하는 선점 방식 | 시간 할당량 |
> 요약: 스케줄러는 정책 기준에 따라 다음 실행 프로세스를 결정함.

## Ⅲ. 절차
```
[Arrival] -> [Queue Insert] -> [Pick by Policy] -> [Execution] -> [Completion]
```
1. 프로세스가 시스템에 도착하면 Ready Queue의 후미에 삽입됨
2. 선택된 알고리즘(FIFO, SJF, RR 등)에 따라 실행할 프로세스를 추출함
3. 선점형(RR 등)의 경우 Time Slice 만료 시 다시 큐로 복귀함
4. 실행 완료 시 프로세스 반환 시간(Turnaround Time) 산출 및 자원 회수
> 요약: 정책별 기준에 따라 대기 시간, 응답 시간, 처리량의 균형이 달라짐.

## Ⅳ. 문제점
- 원인: FIFO에서 긴 프로세스가 앞에 있을 때 발생하는 호위 효과(Convoy Effect)
- 원인: SJF에서 짧은 작업이 계속 도착하면 긴 프로세스의 대기 시간이 과도하게 길어짐

## Ⅴ. 개선방안
- (단기) RR의 타임 퀀텀을 작업 특성에 맞춰 조정하여 응답 지연과 스위칭 비용 균형화
- (중기) 에이징(Aging) 기법을 도입하여 오래 대기한 프로세스 우선순위 상향
- (장기) 다단계 피드백 큐(MLFQ) 등 복합 스케줄링 모델로 전환하여 유연성 증대

## Ⅵ. 전망
- 클라우드 워크로드의 가변성에 대응하는 머신러닝 기반 동적 스케줄링 기술이 부각됨
- 서버와 모바일 환경에서는 전력 소모와 지연 시간을 함께 고려한 스케줄링 정책이 활용됨

## 작성 근거(검토용)

- FIFO, SJF, RR은 우열 단정이 아니라 도착 시간, CPU burst, 시간 할당량이라는 선택 절차로 구분해야 함
- 공통 목표를 과장하지 않고 대기 시간, 응답 시간, 처리량의 균형으로 표현해 정책별 차이를 남김
