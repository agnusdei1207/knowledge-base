## Ⅰ. 개요
- 대용량 데이터를 처리하기 위해 테이블이나 데이터베이스를 작은 단위로 쪼개는 기법임.
- 관리의 효율성, 성능 향상, 가용성 확보를 목적으로 함.
- 출제 의도: 수평/수직 분할 전략과 데이터 분산 처리 메커니즘 이해.

## Ⅱ. 구성요소
- 분할 기법 분류
[Table] -> [Partition (Local)] / [Shard (Distributed)]

| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Partitioning | 하나의 DB 내에서 테이블을 논리적으로 분할함 | 큰 서랍장 칸막이 |
| Sharding | 여러 대의 DB 서버로 데이터를 물리적으로 분산함 | 서랍장 여러 개 배치 |
| Shard Key | 데이터를 나눌 기준이 되는 속성 (Hash, Range 등) | 분류 기준표 |
> 요약: 내부적 분할(파티셔닝)과 외부적 분산(샤딩)을 통해 확장성 확보함.

## Ⅲ. 절차
- 샤딩 적용 단계
[Data Analysis] -> [Key Selection] -> [Mapping] -> [Routing]

1. 부하 분석: 데이터 증가 속도 및 쿼리 패턴을 분석하여 샤딩 필요성 검토함.
2. 샤드 키 선정: 고른 분산을 위해 카디널리티가 높은 속성을 선택함.
3. 분산 룰 정의: 범위(Range), 해시(Hash), 리스트(List) 분할 방식 확정함.
4. 라우팅 구현: 애플리케이션 혹은 미들웨어에서 특정 샤드로 쿼리 전달함.
> 요약: 적절한 키를 기반으로 데이터를 분산 배치하고 접근 경로를 제어함.

## Ⅳ. 문제점
- 조인 연산의 복잡도 급증 및 데이터 재배치(Re-sharding) 시의 높은 비용.

## Ⅴ. 개선방안
- 일관된 해싱(Consistent Hashing) 사용 및 분산 트랜잭션 최소화 설계.

## Ⅵ. 전망
- DB 엔진 차원에서 자동 샤딩과 자동 리밸런싱을 지원하는 클라우드 서비스 주류.
- 애플리케이션 수정 없이 확장 가능한 투명 샤딩(Transparent Sharding) 기술 진화.
