## Ⅰ. 개요
- 정의: 물리 메모리보다 큰 프로그램을 실행하기 위한 가상 주소 기법과 메모리 과부하 현상
- 배경: 한정된 RAM 자원을 효율적으로 분할 사용하고 프로세스 간 메모리 보호 강화 필요
- 출제 의도: 요구 페이징(Demand Paging) 메커니즘과 스래싱 발생 시 시스템 성능 영향 파악

## Ⅱ. 구성요소
```
[ Virtual Addr ] -> [ MMU ] -> [ Physical Addr ]
      |               |              |
      +-> [Page Table]+              +-> [ RAM / Swap ]
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| MMU | 가상 주소를 물리 주소로 변환하는 하드웨어 유닛 | 주소 통역사 |
| 페이지 폴트 | 필요한 데이터가 메모리에 없어 디스크에서 로드하는 인터럽트 | 재고 없음 알림 |
| 워킹 셋 | 프로세스가 일정 시간 동안 집중적으로 참조하는 페이지 집합 | 즐겨찾기 도구 |
> 요약: 가상 메모리는 추상화를 통해 메모리 확장을, 스래싱은 과도한 스왑 오버헤드를 의미함.

## Ⅲ. 절차
```
[CPU Access] -> [Page Fault] -> [Swap In] -> [Update Table] -> [Restart]
```
1. CPU가 가상 주소를 참조하면 MMU가 페이지 테이블을 조회함
2. 해당 페이지가 메모리에 없으면(Invalid bit) 페이지 폴트 트랩 발생
3. OS는 디스크 스왑 영역에서 해당 페이지를 찾아 빈 프레임에 적재(Swap-in)
4. 페이지 테이블을 갱신하고 중단되었던 명령어를 다시 실행함
> 요약: 필요한 시점에 메모리를 할당(Demand Paging)하여 자원 효율을 극대화함.

## Ⅳ. 문제점
- 원인: 다중 프로그래밍 정도가 너무 높아 프로세스당 프레임 수가 워킹 셋보다 적어짐
- 원인: CPU 이용률은 낮은데 I/O(Paging)만 무한 반복되어 시스템이 마비되는 스래싱 발생

## Ⅴ. 개선방안
- (단기) 워킹 셋 알고리즘이나 PFF(Page Fault Frequency)를 활용하여 적정 프레임 할당
- (중기) 다중 프로그래밍 정도(Degree of Multiprogramming)를 낮추어 메모리 여유 확보
- (장기) 고속 SSD 저장장치 도입 및 압축 메모리(ZRAM) 기술 적용으로 I/O 지연 단축

## Ⅵ. 전망
- 지속적인 메모리 가격 하락에도 불구하고, 테라바이트 급 빅데이터 처리를 위한 가상화 기술은 필수적임
- 비휘발성 메모리(NVM)와 결합하여 스왑 지연을 혁신적으로 줄인 통합 메모리 계층 구조가 주류가 될 것임
