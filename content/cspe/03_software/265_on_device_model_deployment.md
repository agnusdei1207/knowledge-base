# 📖 【암기용】 개념 완전 이해

> 목적: 온디바이스 AI 모델 배포를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 온디바이스 AI 모델 배포는 학습된 모델을 **경량화(모델 압축)**해 서버가 아닌 모바일·PC·임베디드 같은 **엣지 단말**에서 직접 추론하도록 변환·최적화·배포하는 방식이다.
- **왜 필요한가**: 서버 추론은 매 요청마다 네트워크를 왕복해야 하고, 민감한 원본 데이터를 서버로 전송해야 하며, 오프라인에서는 아예 동작하지 않는다. 이 세 가지 제약을 단말 내부 추론으로 없앤다.
- **핵심 직관**: 매번 본사에 전화로 물어보는 대신, 현장 직원이 손에 든 요약 매뉴얼만 보고 그 자리에서 즉시 판단하는 구조다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 온디바이스 추론(Edge Inference) | 모델 연산을 서버가 아니라 단말 하드웨어에서 직접 수행하는 것 — 이 기술의 **본질** | 본사에 안 물어보고 현장에서 즉시 결정 |
| TFLite | 모바일·임베디드 전용 경량 추론 런타임(TensorFlow 계열) | 요약본 매뉴얼 |
| ONNX | 서로 다른 학습 프레임워크의 모델을 공통 포맷으로 바꿔주는 교환 표준 | 다른 언어로 된 문서를 표준 서식으로 번역 |
| 양자화(Quantization) | 가중치를 32비트 실수(FP32)에서 8비트 정수(INT8) 등으로 표현 정밀도를 낮춰 크기·연산량을 줄이는 기법 | 정밀 저울 눈금을 성긴 눈금으로 바꿔 계산을 단순화 |
| 프루닝(Pruning) | 출력에 거의 기여하지 않는 가중치·연결을 잘라내는 기법 | 안 쓰는 가지를 쳐내 나무를 가볍게 |
| 지식증류(Knowledge Distillation) | 크고 정확한 교사 모델의 출력을 작은 학생 모델이 모방하도록 학습시키는 기법 | 고수의 요약 강의를 듣고 핵심만 배우는 것 |
| NPU/GPU/CPU 델리게이트 | 추론 연산을 어떤 하드웨어 가속기에 위임할지 지정하는 설정 | 작업을 전문 담당 부서에 배정 |
| OTA(Over-The-Air) | 앱스토어 재배포 없이 네트워크로 모델 파일만 갱신하는 방식 | 방송 전파로 소프트웨어를 업데이트 |
| calibration dataset | 양자화 시 값의 분포 범위를 정하기 위해 사용하는 대표 샘플 데이터 | 저울을 보정할 때 쓰는 표준 추 |

## 깊이 이해

### 왜 필요했나 — 서버 추론의 세 가지 한계
- 지연: 서버 추론은 요청마다 네트워크 왕복이 들어가 실시간성이 떨어진다(왕복 자체가 수십~수백 ms).
- 개인정보: 카메라·마이크 원본 데이터를 서버로 보내야 해서 민감정보 전송 부담이 생긴다.
- 가용성: 네트워크가 끊기는 환경(공장, 지하, 해외 로밍)에서는 서버 추론 자체가 불가능하다.
- 온디바이스 추론은 이 세 문제를 단말 내부 연산으로 해결하지만, 대신 단말의 제한된 메모리·배터리·연산력이라는 새 제약을 받는다.

### 작동 원리 — 변환부터 추론까지
- 학습은 서버(GPU)에서 PyTorch·TensorFlow로 그대로 진행한다.
- 학습된 모델을 TFLite 또는 ONNX 포맷으로 변환한다. 이때 프레임워크 전용 연산자가 대상 런타임에서 지원되는지 확인해야 한다(미지원 연산자가 있으면 변환이 실패하거나 일부 레이어를 서버로 남겨야 한다).
- 양자화·프루닝·지식증류로 모델을 압축한다.
- 앱이 모델 파일을 내장하거나 OTA로 내려받고, 단말의 NPU·GPU·CPU 중 하나에 위임해 추론한다.

### 구체 수치로 보는 양자화 효과
- FP32는 가중치 하나에 4바이트, INT8은 1바이트를 쓴다. 이론상 4배 압축이 가능하다.
- 예: 120MB FP32 이미지 분류 모델을 INT8로 양자화하면 이론값 30MB에 근접한 32MB 수준으로 줄어든다(연산 그래프 메타데이터 등 오버헤드 때문에 정확히 4배는 아니다).
- 대신 정밀도가 낮아진 만큼 정확도가 떨어질 수 있어, calibration dataset으로 값 분포를 보정하고 A/B 테스트로 정확도 손실을 1~3% 이내로 관리하는 것이 실무 목표치다.
- 크기가 줄어든 모델을 모바일 NPU에서 실행하면 p95 추론 지연 50ms 이하를 목표로 잡을 수 있다 — 압축을 안 하면 이 목표를 못 맞춰 배터리 소모와 발열도 함께 커진다.

### 판별 원리 — 언제 서버, 언제 온디바이스인가
- 모델이 매우 크거나(대형 LLM), 중앙에서 모든 사용자의 모델 버전을 즉시 통제해야 하면 서버 추론이 유리하다.
- 지연에 민감하거나(p95 50ms 이하 요구), 오프라인 동작이 필요하거나, 원본 데이터를 단말 밖으로 못 보내는 규제가 있으면 온디바이스가 유리하다.
- 실무에서는 둘을 같이 쓴다 — 자주 바뀌는 대형 로직은 서버, 반응성이 중요한 소형 로직(얼굴 인식, 음성 웨이크워드)은 온디바이스로 나눈다.

### 비유와 흔한 오해
- **비유**: 대형 사전을 서버에 두고 매번 검색하는 대신, 자주 쓰는 핵심 단어장만 휴대폰에 담아 그 자리에서 찾는 것과 같다.
- **오해**: 온디바이스 배포가 서버를 완전히 없애는 것은 아니다. 모델 버전 관리, OTA 배포, 실패 시 이전 버전으로의 롤백, 배포 후 크래시율 같은 운영 체계(MLOps)가 여전히 서버 쪽에 필요하다.

## 연결 개념
- TFLite - 모바일·임베디드 추론 런타임 (변환 대상 포맷 중 하나)
- ONNX - 프레임워크 간 모델 교환 포맷 (변환 대상 포맷 중 하나)
- MLOps - 모델 버전, 배포, 모니터링 관리 (온디바이스 배포 이후 운영을 다루는 상위 체계)

## Ⅰ. 개요 및 필요성

- 개요: 온디바이스 AI 모델 배포는 단말 내부 추론 방식이다.
- 배경: 서버 추론은 네트워크 지연과 개인정보 전송 부담이 있고 오프라인 환경에서 서비스가 중단될 수 있다.
- 필요성: TFLite·ONNX 기반 경량 배포로 지연시간, 데이터 전송량, 클라우드 비용을 통제해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Trained Model -> Conversion(TFLite/ONNX) -> Optimization
              -> App/Runtime -> CPU/GPU/NPU Inference -> Telemetry/OTA
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 모델 변환 | PyTorch·TensorFlow 모델을 TFLite·ONNX로 변환 | 연산자 호환성 확인 |
| 최적화 | 양자화, 프루닝, 지식증류 | 정확도 손실 1~3% 이내 목표 |
| 단말 런타임 | CPU·GPU·NPU에서 추론 실행 | Android NNAPI, Core ML 연계 |
| 운영 배포 | OTA, 버전 관리, 롤백, 텔레메트리 | 모델 파일 무결성 검증 |

> 요약: 온디바이스 배포는 변환, 최적화, 런타임, OTA 운영이 하나의 릴리스 체계로 묶인다.

## Ⅲ. 동작원리 및 흐름도

```text
모델 학습 -> 포맷 변환 -> 양자화/검증 -> 앱 패키징 또는 OTA
-> 단말 추론 -> 지연/오류 측정 -> 모델 롤백 또는 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 모델 변환 | 지원 연산자 100% 확인 |
| 2 | 경량화 | 크기 50MB 이하, 정확도 손실 3% 이내 |
| 3 | 단말 성능 검증 | p95 추론 50ms 이하, 배터리 사용량 측정 |
| 4 | OTA 운영 | 서명 검증, 롤백 1단계 이내 |

> 요약: 온디바이스 AI는 모델 정확도와 단말 자원 제약을 동시에 통과해야 배포 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 변환 검증: PyTorch/TensorFlow 모델을 ONNX 또는 TFLite로 변환하고 지원 연산자와 정확도 손실 3% 이내 확인
2. 단말 최적화: INT8 양자화, NPU Delegate, 배치 크기 1 기준 p95 50ms 이하 벤치마크 수행
3. OTA 운영: 모델 서명 검증, 5% 단계 배포, crash-free 99.5% 미만 시 즉시 이전 모델로 롤백

**결론 (2줄):**
- 기술사 판단: 개인정보·오프라인·저지연 요구가 있으면 온디바이스, 대형 모델·중앙 통제가 우선이면 서버 추론을 선택함
- 향후 방향: 온디바이스 AI는 경량 모델, NPU, 연합학습, MLOps OTA가 결합된 엣지 AI 운영으로 발전함
