# 📖 【암기용】 개념 완전 이해

> 목적: 온디바이스 AI 모델 배포를 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: AI 모델을 서버가 아닌 모바일·PC·임베디드 장치에서 직접 실행하도록 변환·최적화·배포하는 방식
- **왜 필요한가**: 네트워크 지연, 개인정보 전송, 오프라인 환경, 클라우드 추론 비용 문제를 줄이기 위해 기기 내부 추론이 필요하다.
- **핵심 직관**: 매번 본사에 물어보지 않고 현장 직원이 휴대 단말에서 즉시 판단하는 구조이다.

## 깊이 이해
- **배경·문제의식**: 서버 추론은 모델 교체와 중앙 관리가 쉽지만, 지연시간과 개인정보 전송 부담이 있다. 온디바이스 추론은 모델 크기, 배터리, 칩셋 호환성 제약을 해결해야 한다.
- **작동 원리**: 학습 모델을 TFLite 또는 ONNX로 변환하고, 양자화·프루닝·지식증류로 크기와 연산량을 줄인다. 앱은 모델 파일을 포함하거나 OTA로 내려받아 NPU, GPU, CPU에서 추론한다.
- **비유**: 대형 사전을 서버에 두고 검색하는 대신, 핵심 단어장만 휴대폰에 넣어 현장에서 즉시 찾는 방식이다.
- **구체 예시**: 120MB FP32 이미지 분류 모델을 INT8 양자화로 32MB로 줄이고, 모바일 NPU에서 p95 50ms 이하 추론을 목표로 설정한다.
- **흔한 오해·주의점**: 온디바이스 배포는 서버 제거가 아니다. 모델 버전 관리, 롤백, 성능 모니터링, 개인정보 처리 기준이 필요하다.

## 연결 개념
- TFLite - 모바일·임베디드 추론 런타임
- ONNX - 프레임워크 간 모델 교환 포맷
- MLOps - 모델 버전, 배포, 모니터링 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 온디바이스 AI는 모델 변환 기술보다 지연, 개인정보, 배터리, OTA 운영 기준을 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 온디바이스 AI 모델 배포는 학습 모델을 TFLite·ONNX 등 경량 런타임으로 변환해 단말에서 추론하는 배포 방식이다.
> 2. **가치**: p95 지연 50ms, 오프라인 동작, 원본 데이터 단말 보관, 클라우드 추론 비용 절감을 목표로 한다.
> 3. **판단 포인트**: 모델 크기, 정확도 손실, 배터리 소모, 칩셋 호환성, OTA 롤백 기준을 동시에 검토한다.

## Ⅰ. 개요 및 필요성

- 개요: 온디바이스 AI 모델 배포는 단말 내부 추론 방식이다.
- 배경: 서버 추론은 네트워크 지연과 개인정보 전송 부담이 있고 오프라인 환경에서 서비스가 중단될 수 있다.
- 필요성: TFLite·ONNX 기반 경량 배포로 지연시간, 데이터 전송량, 클라우드 비용을 통제해야 한다.

---

## Ⅱ. 구조 및 구성요소

```text
Trained Model -> Conversion(TFLite/ONNX) -> Optimization
              -> App/Runtime -> CPU/GPU/NPU Inference -> Telemetry/OTA
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 모델 변환 | PyTorch·TensorFlow 모델을 TFLite·ONNX로 변환 | 연산자 호환성 확인 |
| 최적화 | 양자화, 프루닝, 지식증류 | 정확도 손실 1~3% 이내 목표 |
| 단말 런타임 | CPU·GPU·NPU에서 추론 실행 | Android NNAPI, Core ML 연계 |
| 운영 배포 | OTA, 버전 관리, 롤백, 텔레메트리 | 모델 파일 무결성 검증 |

> 요약: 온디바이스 배포는 변환, 최적화, 런타임, OTA 운영이 하나의 릴리스 체계로 묶인다.

---

## Ⅲ. 동작원리 및 흐름도

```text
모델 학습 -> 포맷 변환 -> 양자화/검증 -> 앱 패키징 또는 OTA
-> 단말 추론 -> 지연/오류 측정 -> 모델 롤백 또는 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 모델 변환 | 지원 연산자 100% 확인 |
| 2 | 경량화 | 크기 50MB 이하, 정확도 손실 3% 이내 |
| 3 | 단말 성능 검증 | p95 추론 50ms 이하, 배터리 사용량 측정 |
| 4 | OTA 운영 | 서명 검증, 롤백 1단계 이내 |

> 요약: 온디바이스 AI는 모델 정확도와 단말 자원 제약을 동시에 통과해야 배포 가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 변환 검증: PyTorch/TensorFlow 모델을 ONNX 또는 TFLite로 변환하고 지원 연산자와 정확도 손실 3% 이내 확인
2. 단말 최적화: INT8 양자화, NPU Delegate, 배치 크기 1 기준 p95 50ms 이하 벤치마크 수행
3. OTA 운영: 모델 서명 검증, 5% 단계 배포, crash-free 99.5% 미만 시 즉시 이전 모델로 롤백

**결론 (2줄):**
- 기술사 판단: 개인정보·오프라인·저지연 요구가 있으면 온디바이스, 대형 모델·중앙 통제가 우선이면 서버 추론을 선택함
- 향후 방향: 온디바이스 AI는 경량 모델, NPU, 연합학습, MLOps OTA가 결합된 엣지 AI 운영으로 발전함
