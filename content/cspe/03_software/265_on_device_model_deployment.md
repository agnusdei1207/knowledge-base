## Ⅰ. 개요
- **정의**: AI 모델을 클라우드가 아닌 엣지 디바이스(스마트폰·IoT)에서 로컬 추론하도록 경량화하여 배포하는 기법
- **배경/필요성**: 네트워크 지연·프라이버시·오프라인 요구로 클라우드 의존 추론의 한계가 부각됨
- **비유**: 중앙 도서관(클라우드)에 매번 가는 대신 개인 서재(디바이스)에 핵심 참고서를 비치하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지 AI 배포 전략 이해 | 모델 경량화 기법(양자화·증류·가지치기) | 경량화 기법 간 트레이드오프 명시 |

> 요약: 온디바이스 배포는 모델을 경량화하여 엣지에서 저지연·프라이버시 보장 추론을 실현하는 기법임

## Ⅱ. 구성요소
```text
[Full Model] --경량화--> [Compressed Model] --변환--> [Runtime]
     |                        |                        |
     v                        v                        v
[Quantization]          [Model Format]           [HW Accelerator]
[Distillation]          (ONNX/TFLite)            (NPU/GPU/DSP)
[Pruning]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Quantization | FP32를 INT8/INT4로 변환하여 연산량과 모델 크기를 축소함 | 고화질 이미지를 적정 해상도로 압축하는 것 |
| Distillation | 대형 모델의 지식을 소형 모델로 전이하여 정확도를 유지함 | 교수의 강의를 요약 교재로 압축하는 것 |
| HW Accelerator | NPU·DSP 등 전용 하드웨어로 추론 연산을 가속함 | 범용 공구 대신 전용 지그를 사용하는 것 |

> 요약: 양자화·증류·가지치기로 경량화하고 전용 하드웨어에서 가속 추론을 수행함

## Ⅲ. 절차
```text
모델 학습 --> 경량화/변환 --> 디바이스 배포 --> 온디바이스 추론
    |              |               |               |
    v              v               v               v
  클라우드     양자화/증류      OTA배포        로컬실행
```
- 1단계: 클라우드에서 풀사이즈 모델을 학습함
- 2단계: 양자화·증류·가지치기를 적용하고 타깃 포맷(ONNX/TFLite)으로 변환함
- 3단계: OTA 업데이트 또는 사전 탑재 방식으로 디바이스에 배포함
- 4단계: NPU/GPU 가속기를 활용하여 디바이스에서 로컬 추론을 수행함

> 요약: 학습-경량화-배포-추론의 4단계로 온디바이스 AI를 실현함

## Ⅳ. 문제점
- 정확도 손실: 경량화 과정에서 모델 성능이 저하됨 — 사용자 체감 품질이 하락함
- 디바이스 파편화: HW 사양·가속기 종류가 다양함 — 모델 호환성 검증 비용이 증가함
- 업데이트 관리: 배포된 모델의 버전 관리가 복잡함 — 구버전 모델이 잔존하여 일관성이 저하됨

> 요약: 정확도 손실·디바이스 파편화·버전 관리가 온디바이스 배포의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 정확도-크기 트레이드오프를 자동 탐색하는 AutoML 기반 경량화 파이프라인 도입
2. 중기: 통합 런타임(ONNX Runtime 등)으로 HW 추상화 계층을 표준화
3. 장기: A/B 테스트 기반 점진적 모델 롤아웃과 자동 롤백 체계를 구축

> 요약: 자동 경량화-런타임 표준화-배포 자동화로 단계적 성숙이 필요함

## Ⅵ. 전망
- 발전 방향: 디바이스에서 파인튜닝까지 수행하는 On-Device Learning으로 진화함
- 기술사적 판단: NPU 탑재 확대와 함께 온디바이스 AI가 표준 사용자 경험으로 정착될 것임
- 기술사 제언: 디바이스 타깃 프로파일링과 경량화 자동화를 MLOps 파이프라인에 통합할 필요
