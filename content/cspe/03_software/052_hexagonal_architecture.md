## 미리 알고가기

- 헥사고날 아키텍처는 도메인 핵심을 외부 기술로부터 분리하는 구조임
- 포트는 내부가 요구하는 추상 인터페이스이고 어댑터는 외부 기술 연결 구현체임
- 테스트 용이성과 기술 교체성이 주요 장점임

## Ⅰ. 개요

- **정의/개념**: 헥사고날 아키텍처는 애플리케이션 핵심 도메인을 중심에 두고, 외부 시스템과의 연결을 포트와 어댑터로 분리해 비즈니스 로직이 인프라 기술에 직접 의존하지 않도록 만드는 아키텍처 패턴임
- **배경/필요성**: 도메인 로직이 프레임워크와 DB와 메시징 구현에 묶이면 테스트와 교체와 확장이 어려워지므로, 기술 변화에 덜 흔들리는 경계가 필요함

## Ⅱ. 특징

- 도메인 핵심을 외부 기술로부터 분리해 테스트가 쉬움
- DB와 API와 메시지 브로커 교체 시 영향 범위를 줄일 수 있음
- 작은 시스템에는 구조가 다소 무거워질 수 있음
- 포트 설계가 부정확하면 오히려 추상화 계층만 늘어남

## Ⅲ. 종류 및 비교

| 판단 기준 | 계층형 구조 | 헥사고날 아키텍처 |
|:---|:---|:---|
| 의존 방향 | 상위에서 하위 기술 계층으로 흐르기 쉬움 | 도메인 중심으로 외부가 안쪽에 의존 |
| 장점 | 단순 이해 쉬움 | 테스트와 기술 교체 유리 |
| 한계 | 도메인과 인프라 결합 위험 | 초기 구조 설계 비용 큼 |
| 적합 환경 | 단순 CRUD | 도메인 복잡도와 통합 다양성 높은 시스템 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Domain Core | 핵심 비즈니스 규칙을 담아 외부 기술과 독립적으로 유지되는 중심 영역임 |
| Port Interface | 도메인이 필요로 하는 입출력 계약을 정의해 구현 기술을 숨김 |
| Adapter | 웹과 DB와 메시징 같은 외부 기술을 포트 계약에 맞춰 연결하는 구현층임 |
| Dependency Boundary | 의존 방향을 안쪽 도메인으로 향하게 강제해 기술 결합을 줄이는 구조 경계임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 도메인 규칙 정의 | --> | 포트 설계      | --> | 어댑터 구현    | --> | 교체/테스트 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **도메인 규칙 정의**: 핵심 비즈니스 규칙을 외부 기술 없이 정리함
2. **포트 설계**: 도메인이 필요로 하는 입력과 출력 계약을 만든다
3. **어댑터 구현**: API와 DB와 메시지 연동을 포트에 맞게 구현함
4. **교체 및 테스트 검증**: 모의 어댑터와 실제 어댑터를 바꿔가며 검증함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 단순 CRUD 시스템에 과도 적용하면 포트와 어댑터 계층만 늘어 개발 속도가 떨어질 수 있음
   - 해결방안: 도메인 복잡도 기준으로 적용 대상을 선별하고 abstraction overhead score와 delivery lead time으로 검증함
2. 문제: 포트가 구현 세부를 그대로 노출하면 구조만 분리되고 결합은 그대로 남을 수 있음
   - 해결방안: 도메인 언어 중심 포트를 설계하고 port purity score와 adapter churn rate로 검증함
3. 문제: 팀이 의존 방향 원칙을 지키지 않으면 시간이 지날수록 도메인에 인프라 코드가 침투할 수 있음
   - 해결방안: 아키텍처 테스트와 리뷰를 운영하고 dependency rule violation count와 test isolation score로 검증함

## Ⅶ. 적용 사례

- 복잡한 주문 도메인 서비스에서는 헥사고날 구조를 사용하고, test isolation score와 adapter churn rate로 결과를 확인함
- 외부 연동이 많은 금융 서비스에서는 포트 기반 교체를 설계하고, port purity score와 integration defect count로 결과를 확인함
- 아키텍처 규율이 중요한 플랫폼 팀에서는 의존성 테스트를 운영하고, dependency rule violation count와 delivery lead time로 결과를 확인함

## Ⅷ. 결론

헥사고날 아키텍처의 핵심은 모양이 육각형인 데 있지 않고 도메인 규칙을 외부 기술 변화로부터 지키는 의존 방향 설계에 있음.
