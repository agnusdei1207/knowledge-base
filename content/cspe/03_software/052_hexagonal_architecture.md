## 미리 알고가기

- 포트는 도메인 내부가 외부에 요구하는 추상 인터페이스임
- 어댑터는 웹, DB, 메시징 같은 외부 기술을 포트에 맞춰 연결하는 구현체임
- 의존 방향은 바깥 기술이 안쪽 도메인에 맞추는 쪽으로 유지해야 함

## Ⅰ. 개요

- **정의/개념**: 헥사고날 아키텍처는 애플리케이션 핵심 도메인을 중심에 두고 외부 시스템과의 연결을 포트와 어댑터로 분리해 비즈니스 로직이 인프라 기술에 직접 의존하지 않도록 만드는 아키텍처 패턴임.
- **배경/필요성**: 도메인 로직이 프레임워크와 DB와 메시징 구현에 묶이면 테스트와 교체와 확장이 어려워지므로, 기술 변화에 덜 흔들리는 경계가 필요함.

## Ⅱ. 특징

- 도메인 핵심을 외부 기술로부터 분리해 테스트와 유지보수를 쉽게 만듦
- DB와 API와 메시지 브로커 교체 시 영향 범위를 줄일 수 있음
- 단순 CRUD 시스템에는 구조가 다소 무거워질 수 있음
- 포트 설계가 구현 세부를 그대로 노출하면 추상화만 늘어날 수 있음

## Ⅲ. 종류 및 비교

| 구분 | 계층형 구조 | 헥사고날 아키텍처 |
|:---|:---|:---|
| 의존 방향 | 상위 계층이 하위 기술 계층에 직접 의존하기 쉬움 | 외부 기술이 도메인 포트에 맞춰 안쪽으로 의존함 |
| 구조상 장점 | 이해와 구현이 단순해 초기 개발이 빠름 | 테스트와 기술 교체와 도메인 보호에 유리함 |
| 구조상 한계 | 도메인과 인프라 결합이 누적되기 쉬움 | 초기 포트 설계와 구조 정리가 더 필요함 |
| 적합한 환경 | 단순 CRUD와 짧은 수명 서비스에 맞음 | 도메인 복잡도와 외부 연동 변화가 큰 시스템에 맞음 |

> 요약: 헥사고날 아키텍처는 모양보다 의존 방향을 도메인 중심으로 고정하는 데 의미가 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Domain Core | 핵심 비즈니스 규칙을 담아 외부 기술과 독립적으로 유지되는 중심 영역임 |
| Port Interface | 도메인이 필요로 하는 입력과 출력 계약을 정의해 구현 기술을 숨김 |
| Adapter | 웹, DB, 메시징 같은 외부 기술을 포트 계약에 맞춰 연결하는 구현층임 |
| Dependency Boundary | 의존 방향을 도메인 안쪽으로 향하게 강제해 기술 결합을 줄이는 경계임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 도메인 규칙 정의 | --> | 포트 설계      | --> | 어댑터 구현    | --> | 교체/테스트 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **도메인 규칙 정의**: 핵심 비즈니스 규칙을 외부 기술 없이 정리함
2. **포트 설계**: 도메인이 필요로 하는 입력과 출력 계약을 정의함
3. **어댑터 구현**: API, DB, 메시지 연동을 포트에 맞게 구현함
4. **교체 및 테스트 검증**: 모의 어댑터와 실제 어댑터를 바꿔가며 검증함

## Ⅵ. 실무 적용 및 유의점

1. 외부 연동이 많고 핵심 규칙이 복잡한 서비스에서는 헥사고날 구조가 유리하지만 단순 CRUD까지 같은 수준으로 감싸면 개발 속도가 떨어지므로 적용 대상을 선별하고 추상화 비용과 기능 반영 시간으로 확인함
2. 장기 운영 플랫폼에서는 도메인 포트가 구현 세부를 노출하지 않도록 아키텍처 테스트를 함께 두고 의존 방향 위반 건수와 포트의 구현 의존 항목 수로 확인함

## Ⅶ. 결론

헥사고날 아키텍처는 도메인 규칙을 기술 변화에서 지키려는 시스템에서 가장 실용적인 구조가 됨.
