# 📖 【암기용】 개념 완전 이해

> 목적: 기술부채 사분면을 처음 봐도 부채의 선악 판단이 아니라 의도와 신중성에 따른 관리 프레임이라는 점을 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: 기술부채를 무모/신중, 의도/비의도 축으로 나눠 원인과 상환 전략을 정하는 모델
- **왜 필요한가**: 모든 부채를 같은 방식으로 처리하면 일정과 품질 판단이 흐려짐. 사분면은 어떤 부채를 즉시 상환하고 어떤 부채를 기록 후 관리할지 구분함.
- **핵심 직관**: 대출도 계획된 투자 대출과 무계획 소비 대출의 처방이 다르듯, 기술부채도 발생 맥락별 처방이 다름.

## 깊이 이해
- **배경·문제의식**: 기술부채는 일정 단축, 지식 부족, 요구 변경, 실험 실패 등 다양한 원인에서 생김. 원인을 구분하지 않으면 책임 추궁과 전면 재작성 논의로 흘러 실행력이 낮아짐.
- **작동 원리**: Martin Fowler의 사분면은 reckless/prudent와 deliberate/inadvertent 두 축을 사용함. 각 항목에 결정 기록, 영향 범위, 상환 시점, 소유자를 붙여 관리함.
- **비유**: 길을 빨리 가려고 유료도로를 탄 결정은 비용을 알고 선택한 것이지만, 길을 몰라 헤맨 것은 학습 부족임. 둘의 사후 조치가 다름.
- **구체 예시**: 출시 마감으로 캐시 무효화 로직을 단순화하고 ADR에 2주 내 개선을 기록했다면 prudent deliberate 부채임. 원인 모른 채 복잡도가 누적된 모듈은 inadvertent 부채임.
- **흔한 오해·주의점**: 사분면은 부채를 정당화하는 면죄부가 아님. 의도한 부채도 이자 지표와 상환 기한이 없으면 무모한 부채로 전환됨.

## 연결 개념
- ADR — 부채 발생 사유와 상환 조건 기록
- Refactoring — 부채 원금 상환 수단
- CMMI — 조직의 프로세스 성숙도 관점에서 부채 관리 체계화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 기술부채 사분면은 부채 유무가 아니라 발생 의도와 판단 수준을 분류해 상환 전략을 달리하는 의사결정 도구이다.

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: Technical Debt Quadrant는 기술부채를 reckless/prudent와 deliberate/inadvertent 축으로 분류하는 모델이다.
> 2. **가치**: 부채 원인·책임·상환 기한·결정 기록을 구분해 즉시 제거, 계획 상환, 학습 개선 전략을 선택하게 함.
> 3. **판단 포인트**: 의도한 부채도 ADR, owner, due date, debt interest 지표가 없으면 관리 실패로 본다.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기술부채 분류 역량 확인 | reckless/prudent, deliberate/inadvertent 2축 | 부채를 단순 나쁜 코드로만 설명 |
| 의사결정 기록 역량 확인 | ADR, 상환 기한, 소유자, 잔여 리스크 | 사분면 이름만 나열하고 관리 절차 누락 |
| 상환 전략 판단 확인 | 즉시 제거, 계획 상환, 학습·표준화 | 모든 부채를 전면 재작성으로 처리 |

> 요약: 이 문제는 부채의 원인과 발생 맥락에 따라 관리·상환 전략을 다르게 제시하는 답안을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 기술부채 원인 분류 모델
- 배경: 단기 선택이 장기 변경 비용으로 전가되더라도 무지, 일정 압박, 의도적 우회, 무모한 설계는 원인과 대응 방식이 다르다.
- 필요성: 의도성·신중성 기준의 사분면으로 부채를 분류해 즉시 상환, 점진 개선, 학습 보완, 의사결정 기록 같은 대응을 선택한다.

---

## Ⅱ. 구조 및 구성요소

```text
Technical Debt Item
  -> Deliberate / Inadvertent
  -> Prudent / Reckless
  -> Quadrant Classification
  -> ADR / Backlog / Repayment Strategy
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Prudent Deliberate | 위험을 알고 의도적으로 선택 | 출시 일정, ADR, 상환일 필요 |
| Prudent Inadvertent | 경험 후 더 나은 방법을 학습 | 회고, 표준 개선으로 처리 |
| Reckless Deliberate | 위험을 알면서 통제 없이 진행 | 즉시 중단·재설계 후보 |
| Reckless Inadvertent | 지식 부족으로 부채 발생 | 교육, 리뷰, 가이드 필요 |
| Debt Register | 부채 항목의 공통 관리대장 | owner, due date, interest 기록 |

> 요약: 사분면은 부채 항목을 의도성과 신중성으로 분류하고, 각 유형별 상환·학습·통제 방안을 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Architecture Decision -> Shortcut or Unknown Risk
  -> Record Context -> Classify Quadrant
  -> Measure Debt Interest -> Select Repayment
  -> Review Due Date -> Close or Reclassify
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 부채 항목과 발생 배경 수집 | PR, incident, ADR 링크 |
| 2 | deliberate/inadvertent 여부 판정 | 선택 당시 대안 검토 존재 여부 |
| 3 | prudent/reckless 여부 판정 | 리스크·상환 계획 기록 여부 |
| 4 | 상환 전략과 기한 결정 | due date 30~90일, owner 지정 |
| 5 | 이자 지표 측정 후 종료 또는 재분류 | lead time, defect, complexity 추세 |

> 요약: 사분면 적용은 부채 항목 기록, 축별 판정, 전략 선택, 이자 측정, 재분류 순서로 수행된다.

## Ⅳ. 특징

| 구분 | 일반 부채 목록 | 기술부채 사분면 | 정량 기준 |
|:---|:---|:---|:---|
| 분류 축 | 심각도 중심 | 의도성·신중성 2축 | 4개 quadrant |
| 산출물 | 개선 티켓 | ADR+부채대장+상환전략 | owner, due date |
| 대응 | 우선순위 모호 | 유형별 처방 | 즉시 제거/계획 상환/교육 |
| 통제 | 리뷰어 판단 | 지표 기반 재평가 | lead time, defect density |
| 조직 학습 | 항목 처리 중심 | 원인 학습 포함 | 회고 액션 완료율 |

> 요약: 사분면은 부채를 단순 목록이 아니라 발생 맥락과 상환 전략이 있는 의사결정 기록으로 만든다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | severity 기반 backlog | quadrant 기반 classification | 원인 분석과 학습이 필요할 때 |
| 비용/성능 | 부채 총량 관리 | 부채 이자와 상환 비용 관리 | lead time 30% 증가 시 상환 |
| 운영/위험 | 담당자 기억 의존 | ADR·owner·due date 관리 | 규제·감사 대상 시스템 |
| 조직 | 개인 책임 논쟁 | 의사결정 품질 개선 | 반복 부채 원인 추적 필요 |

> 요약: 사분면은 부채 규모보다 발생 맥락과 상환 책임을 분명히 해야 하는 조직에 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 부채 정당화 | prudent deliberate 남용 | 승인권자, due date, 이자 지표 필수화 | 기한 초과 부채 0건 |
| 분류 논쟁 | 축 판정 기준 불명확 | 예시 카탈로그와 리뷰 보드 운영 | 재분류 건수 |
| 상환 지연 | 기능 개발 우선 | sprint capacity 10~20% 배정 | 상환 완료율 |
| 지식 부채 반복 | 학습 조치 없음 | 표준·교육·리뷰 체크리스트 반영 | 동일 원인 재발률 |

> 요약: 사분면 리스크는 분류 기준, 승인, 상환 capacity, 학습 조치로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 부채 관리 | owner·due date 등록 100% | debt register 점검 |
| 상환 실행 | 만기 내 상환 90% 이상 | Jira, Git PR |
| 이자 감소 | 변경 리드타임 30% 감소 | DORA, cycle time |
| 학습 효과 | 동일 원인 재발률 20% 이하 | 회고 액션 추적 |

> 요약: 사분면 도입 효과는 등록 완전성, 상환율, 리드타임, 재발률로 확인한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. ADR 템플릿에 선택 배경, 대안, 사분면 유형, debt interest, owner, due date를 필수 항목으로 추가함.
2. 월 1회 아키텍처 리뷰에서 reckless 항목은 즉시 개선 대상으로, prudent deliberate 항목은 30~90일 내 상환 대상으로 분리함.
3. 부채 이자를 lead time, incident count, complexity, duplication 지표로 측정하고 제품 백로그 capacity 10~20%를 상환에 배정함.

**결론 (2줄):**
- 기술사 판단: 일정상 의도한 부채는 ADR과 상환 기한이 있을 때만 허용하고, 무모한 부채는 릴리스 차단 또는 범위 축소로 처리함.
- 향후 방향: 기술부채 사분면은 플랫폼 엔지니어링, 품질 게이트, DORA 지표와 결합해 지속적 설계 거버넌스로 운영됨.
