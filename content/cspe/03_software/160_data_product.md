## 미리 알고가기

- 데이터 제품은 특정 소비 목적에 맞춰 데이터·코드·메타데이터·인터페이스·운영 책임을 묶은 제공 단위임
- Product Owner는 소비자 요구·품질·우선순위·수명주기와 지원 책임을 관리함
- 데이터 인터페이스는 테이블·파일·토픽·API·모델처럼 소비자가 제품을 사용하는 접점임
- 데이터 SLO는 최신성·완전성·가용성·응답 지연처럼 제품의 제공 수준을 측정함
- 발견 가능성은 카탈로그에서 목적·스키마·소유자·품질·접근 절차를 찾을 수 있는 성질임
- 데이터 계약은 제품 인터페이스의 구조·의미·품질·변경 호환성을 소비자와 합의함

## 작성 근거(검토용)

- 데이터 제품은 소비 목적·단일 소유자·인터페이스·계약·SLO·수명주기를 핵심으로 선정함
- 비교표는 원시 Dataset과 제품의 목적·책임·인터페이스·메타데이터·품질·수명주기를 대비함
- 순차 처리보다 제품 경계와 책임이 핵심이므로 Ⅴ절을 생략하고 구성요소의 결합 관계로 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 데이터셋과 제품의 책임 차이를 분명히 함

## Ⅰ. 개요

- **정의/개념**: 데이터 제품은 소비 목적과 소유자를 두고 데이터·변환 코드·메타데이터·인터페이스·계약·SLO를 독립 운영하는 데이터 자산임
- **배경/필요성**: 데이터셋의 위치만 제공해 소비자가 의미·품질·책임자를 다시 찾는 비용을 줄이기 위해 사용성과 운영 책임을 포함한 제품 경계가 필요함

## Ⅱ. 특징

- 제품이 해결할 소비자 문제와 사용 시나리오를 정하고 이에 필요한 데이터 범위를 제한함
- 단일 소유 팀이 변환 코드·데이터·메타데이터·인터페이스·지원과 수명주기를 함께 책임짐
- 계약이 스키마·의미·품질·변경 호환성을, SLO가 최신성·완전성·가용성을 명시함
- 카탈로그가 설명·예제·계보·소유자·접근 절차를 제공해 소비자가 적합성을 판단하게 함
- 사용량·중복 제품·미사용 인터페이스·SLO 위반을 기준으로 제품 개선·폐기를 판단함

## Ⅲ. 종류 및 비교

| 판단 기준 | 원시 Dataset | 데이터 제품 |
|:---|:---|:---|
| 제공 목적 | 생산 시스템의 저장·처리 결과 | 정의된 소비자 문제와 사용 사례 해결 |
| 책임 범위 | 저장 위치·스키마 담당자가 분리될 수 있음 | 한 소유 팀이 코드·데이터·인터페이스 운영 |
| 접근 방식 | 테이블·파일 경로를 직접 해석 | 계약된 테이블·토픽·API와 사용 예제 제공 |
| 메타데이터 | 기술 스키마·위치 중심 | 의미·소유자·계보·품질·정책·지원 포함 |
| 품질 기준 | 생성 작업 성공 여부 중심 | 소비 목적별 SLO와 품질 규칙 공개 |
| 수명주기 | 원천 시스템 변경에 따라 유지 | 버전·호환성·사용량·폐기 계획을 제품으로 관리 |

> 요약: 데이터 제품은 Dataset에 소비 목적·소유권·인터페이스·계약·SLO와 수명주기 책임을 결합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Product Purpose·Consumer | 해결할 업무 질문과 대상 사용자·사용 범위를 정의함 |
| Data·Transform Code | 원천을 수집·정제·집계해 제품 데이터와 재현 가능한 버전을 생성함 |
| Metadata·Contract | 스키마·의미·계보·품질·정책과 변경 호환성을 설명함 |
| Access Interface | 테이블·토픽·API·파일 중 소비 방식과 권한·예제를 제공함 |
| Owner·Support | 단일 책임 팀이 우선순위·장애·질문·변경·폐기를 관리함 |
| SLO·Observability | 최신성·완전성·가용성·사용량과 위반 이력을 측정함 |

```text
Source -> Transform Code -> Data·Metadata·Contract -> Interface -> Consumer
                              |
                         Owner·SLO·Support
```

> 요약: 변환 코드가 만든 데이터와 메타데이터를 계약된 인터페이스로 제공하고 소유 팀이 SLO와 수명주기를 책임짐.

## Ⅵ. 실무 사례

1. 주문 분석 제품은 일별 주문 테이블과 계약·소유자를 제공하고 최신성 SLO·대사 차이를 확인함
2. 서버 상태 제품은 서비스별 지표 API를 제공하고 응답 지연·누락 시계열 수를 확인함

## Ⅶ. 결론

- 데이터 제품은 소비 목적·단일 소유권·계약된 인터페이스·측정 가능한 SLO와 폐기 기준을 갖춰야 함
