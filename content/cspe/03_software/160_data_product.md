## 미리 알고가기

- 데이터 제품은 특정 소비 목적에 맞춰 데이터·코드·메타데이터·인터페이스·운영 책임을 묶은 제공 단위임
- 제품 소유자(Product Owner)는 소비자 요구·품질·우선순위·수명주기와 지원 책임을 관리함
- 데이터 인터페이스는 테이블·파일·토픽·API·모델처럼 소비자가 제품을 사용하는 접점임
- 데이터 SLO는 최신성·완전성·가용성·응답 지연처럼 제품의 제공 수준을 측정함
- 발견 가능성은 카탈로그에서 목적·스키마·소유자·품질·접근 절차를 찾을 수 있는 성질임
- 데이터 계약은 제품 인터페이스의 구조·의미·품질·변경 호환성을 소비자와 합의함

## 작성 근거(검토용)

- 데이터 제품은 소비 목적·단일 소유자·SLO를 비교표의 핵심 판단축으로 선정하고 인터페이스·메타데이터는 Ⅳ 구성요소에서 다룸
- 비교표는 원시 데이터셋과 제품의 제공 목적·책임 범위·품질 기준을 같은 수준에서 대비함
- Ⅴ절은 소비자 문제 발견부터 제품 계약·구현·SLO 운영·폐기까지의 수명주기로 구성함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 데이터셋과 제품의 책임 차이를 분명히 함

## Ⅰ. 개요

- **정의/개념**: 데이터 제품은 소비 목적과 소유자를 두고 데이터·변환 코드·메타데이터·인터페이스·계약·SLO를 독립 운영하는 데이터 자산임
- **배경/필요성**: 데이터셋의 위치만 제공해 소비자가 의미·품질·책임자를 다시 찾는 비용을 줄이기 위해 사용성과 운영 책임을 포함한 제품 경계가 필요함

### 쉽게 이해하기 (학습용)
- 원시 파일을 던져 주는 대신 특정 소비 문제를 해결하는 품질·설명·지원이 있는 데이터 상품임

## Ⅱ. 특징

- 제품이 해결할 소비자 문제와 사용 시나리오를 정하고 이에 필요한 데이터 범위를 제한함
- 단일 소유 팀이 변환 코드·데이터·메타데이터·인터페이스·지원과 수명주기를 함께 책임짐
- 계약이 스키마·의미·품질·변경 호환성을, SLO가 최신성·완전성·가용성을 명시함
- 카탈로그가 설명·예제·계보·소유자·접근 절차를 제공해 발견 가능성을 높이고 소비자가 적합성을 판단하게 함
- 사용량·중복 제품·미사용 인터페이스·SLO 위반을 기준으로 제품 개선·폐기를 판단함

### 쉽게 이해하기 (학습용)
- 제품 이름만 붙여서는 부족하며 단일 소유 팀과 사용 지표·품질 약속·폐기 책임이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 원시 데이터셋 | 데이터 제품 |
|:---|:---|:---|
| 제공 목적 | 생산 시스템의 저장·처리 결과 | 정의된 소비자 문제와 사용 사례 해결 |
| 책임 범위 | 저장 위치·스키마 담당자가 분리될 수 있음 | 한 소유 팀이 코드·데이터·인터페이스·수명주기를 운영 |
| 품질 기준 | 생성 작업 성공 여부 중심 | 소비 목적별 SLO와 품질 규칙 공개 |

> 요약: 데이터 제품은 소비 목적과 단일 소유 팀 책임을 두고 공개된 SLO로 품질을 보장함.

### 쉽게 이해하기 (학습용)
- 원시 데이터셋은 생산 결과, 데이터 제품은 소비 목적과 운영 책임까지 포함함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 제품 목적·소비자 | 해결할 업무 질문과 대상 사용자·사용 범위를 정의함 |
| 데이터·변환 코드 | 원천을 수집·정제·집계해 제품 데이터와 재현 가능한 버전을 생성함 |
| 메타데이터·계약 | 스키마·의미·계보·품질·정책과 변경 호환성을 설명함 |
| 접근 인터페이스 | 테이블·토픽·API·파일 중 소비 방식과 권한·예제를 제공함 |
| 소유자·지원 | 단일 책임 팀이 우선순위·장애·질문·변경·폐기를 관리함 |
| SLO·관측 | 최신성·완전성·가용성·사용량과 위반 이력을 측정함 |

```text
원천 -> 변환 코드 -> 데이터·메타데이터·계약 -> 인터페이스 -> 소비자
                              |
                         소유자·SLO·지원
```

> 요약: 변환 코드가 만든 데이터와 메타데이터를 계약된 인터페이스로 제공하고 소유 팀이 SLO와 수명주기를 책임짐.

### 쉽게 이해하기 (학습용)
- 목적·소비자, 변환 코드와 데이터, 계약·접근 창구, 소유 팀과 품질 계기판으로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
[소비자 문제 발견] -> [제품 경계·소유자·SLO 정의] -> [데이터·코드·계약 구현]
        -> [게시·지원·관측] -> [개선·버전 전환] -> [폐기]
```

1. 해결할 업무 질문과 실제 소비자·사용 결정을 확인함
2. 제품 데이터 경계·단일 소유자·인터페이스·품질 SLO를 정의함
3. 재현 가능한 변환 코드와 메타데이터·계약·접근 예제를 함께 배포함
4. 사용량·SLO·지원 이슈로 개선하고 대체 경로와 예고 기간을 거쳐 폐기함

> 요약: 소비 문제를 제품 계약으로 정의하고 데이터·코드·지원·SLO를 하나의 수명주기로 운영함.

### 쉽게 이해하기 (학습용)
- 손님 문제를 정하고 상품·설명서·품질 보증·고객 지원을 함께 제공하다 안전하게 단종함

## Ⅵ. 실무 사례

1. 주문 분석 제품은 일별 주문 테이블과 계약·소유자를 제공하고 최신성 SLO·대사 차이를 확인함
2. 서버 상태 제품은 서비스별 지표 API를 제공하고 응답 지연·누락 시계열 수를 확인함

### 쉽게 이해하기 (학습용)
- 고객 360 제품에서 활성 소비자·최신성 SLO·지원 응답·버전 전환 성공률을 확인함

## Ⅶ. 결론

- 데이터 제품은 소비 목적·단일 소유권·계약된 인터페이스·측정 가능한 SLO와 폐기 기준을 갖춰야 함
- 산출물 수보다 소비자의 의사결정 개선·재사용·지원 부담과 수명주기 책임으로 제품 가치를 판단해야 함

### 쉽게 이해하기 (학습용)
- 상품 개수보다 실제 손님이 반복 사용하고 품질 약속과 지원이 지켜지는지가 중요함
