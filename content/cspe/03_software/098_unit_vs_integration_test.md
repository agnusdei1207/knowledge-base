## Ⅰ. 개요
- 정의: Unit vs Integration Test의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Component A] --+
                  |--> [Integration Test] --> [System Test]
  [Component B] --+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 단위 테스트 | 모듈/함수 단위 기능 검증 | 벽돌 검사 |
| 통합 테스트 | 모듈 간 인터페이스/상호작용 검증 | 벽 쌓기 |
| 테스트 드라이버 | 상위 모듈 역할을 하는 제어 모듈 | 임시 스위치 |

> 요약: 점진적 상향식/하향식 통합을 통한 계층적 검증임.

## Ⅲ. 절차
- ASCII 흐름도
  Unit A/B -> Stub/Driver -> Integrated Module -> Interface Check

1. 단위 명세 분석: 개별 기능의 입출력 정의함.
2. 단위 테스트: Mock 객체 활용 독립 검증함.
3. 통합 전략 수립: 빅뱅, 상향식, 하향식 중 선택함.
4. 인터페이스 테스트: 모듈 간 데이터 흐름 확인함.

> 요약: 개별 무결성 확보 후 연동 무결성 단계적 확인임.

## Ⅳ. 문제점
- 단위 테스트 시 과도한 Mocking으로 실제 운영 환경과 괴리 발생함.
- 통합 테스트 시 인터페이스 오류 발견 지연에 따른 수정 비용 증가함.

## Ⅴ. 개선방안
- Contract Testing 도입으로 서비스 간 협약 기반 검증 강화함.
- Shift-Left 전략을 통한 통합 테스트 조기 수행 및 자동화함.

## Ⅵ. 전망
- 마이크로서비스(MSA) 확산으로 서비스 간 통신 검증 중요성 급증함.
- CSF: CI/CD 환경 내 자동화된 단위/통합 테스트 스위트 상시 운용임.
