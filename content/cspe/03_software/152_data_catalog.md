## 미리 알고가기

- 기술 메타데이터는 위치·스키마·열 타입·파티션·파일 형식 같은 시스템 정보를 설명함
- 업무 메타데이터는 업무 용어·정의·소유자·사용 목적과 데이터 책임을 설명함
- 운영 메타데이터는 파이프라인 실행·조회 빈도·품질 결과·최신성 같은 사용 상태를 설명함
- 비즈니스 용어집은 업무 용어의 정의·동의어·책임자와 데이터 자산의 연결을 관리함
- 분류(Classification)는 데이터 내용·민감도·규제 범주를 태그로 표시함
- 데이터 계보는 원천·변환 작업·산출물의 관계를 추적함
- 데이터 사전은 한 시스템의 테이블·열·타입·제약조건을 정의한 구조 명세임

## 작성 근거(검토용)

- 카탈로그는 자산 인벤토리·메타데이터 수집·검색·용어·분류·계보·소유권을 핵심으로 선정함
- 비교표는 데이터 사전과 관리 범위·관계 정보·주요 활용을 같은 기준에서 대비함
- 절차는 소스 스캔부터 자산 식별·분류·색인·큐레이션까지 메타데이터 상태 변화를 설명함
- 제목부터 결론까지 모든 문장·표 셀·요약을 5회 전수 검수해 카탈로그와 저장소 역할을 구분함

## Ⅰ. 개요

- **정의/개념**: 데이터 카탈로그는 분산 자산의 기술·업무·운영 메타데이터와 소유권·분류·계보를 수집해 검색·접근 판단을 지원하는 시스템임
- **배경/필요성**: 데이터 위치와 의미를 찾는 시간과 중복 생성을 줄이고 적합한 자산의 품질·민감도·책임자를 확인하기 위해 검색 가능한 인벤토리가 필요함

### 쉽게 이해하기 (학습용)
- 여러 데이터 저장소의 자료 이름·뜻·주인·출처를 한곳에서 찾는 도서관 목록임

## Ⅱ. 특징

- 스캐너·커넥터가 DB·파일·분석 보고서·파이프라인에서 자산과 스키마를 자동 수집함
- 업무 용어집과 기술 자산을 연결해 서로 다른 열 이름을 같은 업무 개념으로 검색함
- 분류·민감도·소유자·품질 결과가 자산 사용 가능성과 접근 절차를 설명함
- 계보가 원천·변환·산출물의 관계를 보여 변경 영향과 장애 원인 분석을 지원함
- 메타데이터 최신성·소유자 지정률·검색 후 자산 선택률로 카탈로그 운영 상태를 측정함

### 쉽게 이해하기 (학습용)
- 검색은 쉬워지지만 자동 수집만 믿으면 낡은 설명·없는 소유자·끊긴 계보가 쌓임

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 사전 | 데이터 카탈로그 |
|:---|:---|:---|
| 관리 범위 | 한 시스템의 테이블·열 정의를 설계자·DB 도구가 수동 기록 | 여러 저장소·파이프라인·보고서 자산을 스캐너·API로 자동 수집 |
| 관계 정보 | 테이블·열의 구조와 제약 | 용어·소유자·분류·계보·사용 관계 |
| 주요 활용 | 개발자·DBA·데이터 모델러가 데이터 구조 이해에 사용 | 분석가·엔지니어·소유자·보안 담당자가 자산 검색·신뢰 판단·접근 요청·영향 분석에 사용 |

> 요약: 데이터 카탈로그는 여러 시스템의 자산을 업무 용어·소유권·분류·계보와 연결해 검색과 사용 판단을 제공함.

### 쉽게 이해하기 (학습용)
- 데이터 사전은 한 시스템의 구조 설명, 카탈로그는 여러 자산의 관계와 사용 판단까지 다룸

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스캐너·커넥터 | 소스의 자산·스키마·분류 후보·실행 정보를 수집함 |
| 메타데이터 저장소·그래프 | 자산과 용어·소유자·계보·정책의 관계를 저장함 |
| 용어집·분류 | 업무 정의와 민감도·규제·도메인 태그를 자산에 연결함 |
| 검색 색인 | 키워드·필터·사용 정보를 색인해 적합한 자산을 찾음 |
| 계보·영향 분석 | 원천·작업·산출물 관계를 추적해 변경 영향을 계산함 |
| 큐레이션·처리 흐름 | 소유자 검토·승인·접근 요청과 메타데이터 수정을 관리함 |

```text
DB·레이크·분석 보고서 -> 스캐너 -> 메타데이터 그래프 -> 검색·계보
                              |
                         용어집·소유자·정책
```

> 요약: 스캐너가 수집한 자산을 메타데이터 그래프가 용어·소유자·분류·계보와 연결해 검색에 제공함.

### 쉽게 이해하기 (학습용)
- 자동 수집기, 메타데이터 관계망, 용어·분류, 검색과 소유자 검토 흐름으로 구성됨

## Ⅴ. 원리 및 절차 흐름도

```text
소스 등록 -> 메타데이터 스캔 -> 자산·관계 식별 -> 분류·색인 -> 소유자 큐레이션
```

1. **소스 등록**: 연결 정보·스캔 범위·자격증명과 담당 소유자를 설정함
2. **스캔 수행**: 스캐너·커넥터가 자산·스키마·열·파티션·실행 메타데이터를 추출함
3. **관계 식별**: 고유 식별자로 기존 자산을 갱신하고 파이프라인·계보 관계를 연결함
4. **분류·색인**: 규칙으로 민감도·업무 용어 후보를 부여하고 검색 색인을 갱신함
5. **큐레이션**: 소유자가 설명·용어·분류·접근 정보를 검토하고 게시함

> 요약: 데이터 카탈로그는 소스 메타데이터를 자산으로 식별하고 분류·계보·소유자 정보와 함께 검색에 게시함.

### 쉽게 이해하기 (학습용)
- 저장소를 훑어 자산을 만들고 뜻·주인·민감도·계보를 붙여 검색에 게시함

## Ⅵ. 실무 사례

1. 분석 테이블 검색은 용어·소유자·최신성을 색인하고 자산 선택률·미소유 자산 수를 확인함
2. 민감 데이터 관리는 자동 분류와 검토 흐름을 적용하고 분류 누락 열·승인 대기 시간을 확인함

### 쉽게 이해하기 (학습용)
- 분석 자산 탐색에서 검색 성공률·소유자 지정률·메타데이터 지연·계보 단절을 확인함

## Ⅶ. 결론

- 데이터 카탈로그는 수집 범위·메타데이터 최신성·검색 정확성·소유자 지정률·계보 연결률을 기준으로 운영해야 함
- 자산 수보다 검색 후 실제 사용률·설명 신뢰도·접근 처리 시간과 소유자의 큐레이션 책임을 관리해야 함

### 쉽게 이해하기 (학습용)
- 목록에 책이 많기보다 원하는 책을 믿고 찾아 실제로 빌릴 수 있어야 함
