# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 카탈로그를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 자산의 위치, 의미, 소유자, 품질, 사용 이력을 검색 가능한 형태로 정리한 목록 체계
- **왜 필요한가**: 데이터가 많아질수록 어떤 테이블이 최신인지, 누가 승인해야 하는지, 어떤 컬럼이 개인정보인지 찾는 시간이 늘어난다. 카탈로그는 데이터 탐색과 사용 승인 과정을 줄인다.
- **핵심 직관**: 도서관 검색 시스템처럼 제목, 저자, 분류, 대출 이력, 이용 규칙을 붙여 데이터 자산을 찾게 해준다.

## 깊이 이해
- **배경·문제의식**: 데이터 웨어하우스와 레이크에 테이블이 수천 개 쌓이면 이름만으로 의미를 알기 어렵다. 데이터 카탈로그는 기술 메타데이터, 업무 용어, 품질 점수, 계보, 권한 정책을 연결해 데이터 사용자가 검증된 자산을 찾게 한다.
- **작동 원리**: 커넥터가 DB와 파일 저장소의 스키마를 수집하고, 사용자는 업무 용어와 태그로 검색한다. 스튜어드가 설명과 소유자를 관리하고, 사용 이력과 품질 규칙은 자동 갱신된다.
- **비유**: 마트 상품 라벨과 재고 시스템의 결합이다. 상품 위치뿐 아니라 원산지, 유통기한, 담당자, 구매 이력까지 제공한다.
- **구체 예시**: `customer_mart` 테이블에 owner, refresh 06:00, PII 컬럼 3개, 품질 점수 97점, 상위 대시보드 12개를 표시하면 재사용 판단이 가능하다.
- **흔한 오해·주의점**: 카탈로그는 위키 문서가 아니다. 자동 수집, 승인 흐름, 품질 점수, 사용 로그가 없으면 오래된 설명 저장소로 전락한다.

## 연결 개념
- 데이터 거버넌스 - 소유자, 승인, 정책 기준 제공
- 데이터 계보 - 카탈로그 자산의 생성과 영향 범위 추적
- 데이터 품질 관리 - 완전성, 정확성, 일관성 점수 제공

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 카탈로그 답안은 검색 도구 소개가 아니라 메타데이터 자동 수집, 업무 의미, 소유권, 품질, 접근 통제의 운영 구조로 작성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 카탈로그는 데이터 자산의 기술/업무/운영 메타데이터를 통합해 탐색과 재사용을 지원하는 관리 체계임.
> 2. **가치**: 데이터 탐색 시간을 시간 단위에서 분 단위로 줄이고, 승인 이력과 품질 점수로 오사용을 통제함.
> 3. **판단 포인트**: 자동 수집 범위, 업무 용어 표준화, 스튜어드 운영, 권한 연계를 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메타데이터 관리 역량 확인 | 기술/업무/운영 메타데이터 구분 | 단순 목록 관리로 축소 |
| 데이터 활용 통제 확인 | owner, steward, 품질 점수, 권한 승인 | 검색 기능만 서술 |
| 운영 지표 설계 확인 | 등록률, 최신성, 검색 성공률, 사용률 | 지표 없이 도입 효과 서술 |

> 요약: 데이터 카탈로그는 데이터 찾기 기능보다 신뢰 가능한 자산을 판별하는 운영 지표가 채점 포인트임.

---

## Ⅰ. 개요 및 필요성

데이터 카탈로그는 데이터 자산 검색과 이해를 위한 메타데이터 관리 체계임. 테이블, 파일, API, 리포트가 증가하면 의미 중복과 오사용이 발생한다. 카탈로그는 자산 위치, 의미, 소유자, 품질, 계보를 묶어 데이터 재사용 기준을 제공한다.

---

## Ⅱ. 구조 및 구성요소

```text
Data Source -> Metadata Connector -> Catalog Repository -> Search/Glossary -> Approval/Access
                                      +-> Quality Score
                                      +-> Usage Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 커넥터 | DB, Lake, BI, API 메타데이터 수집 | JDBC, REST, object storage |
| 저장소 | 스키마, 태그, 설명, owner 보관 | OpenMetadata, DataHub |
| 검색/용어집 | 업무 용어와 데이터 자산 연결 | synonym, domain, glossary |
| 접근 승인 | 사용 신청, 승인, 감사로그 연결 | SSO, RBAC 연계 |

> 요약: 데이터 카탈로그는 커넥터, 저장소, 검색, 승인 흐름이 결합될 때 운영 체계가 됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
자산 스캔 -> 메타데이터 적재 -> 태그/용어 매핑 -> 품질/계보 연결 -> 검색/승인/사용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 소스 시스템 스캔 | 자산 등록률 95% 이상 |
| 2 | 스키마와 샘플 통계 적재 | 수집 지연 24시간 이하 |
| 3 | 업무 용어, PII 태그, owner 매핑 | owner 누락 0건 |
| 4 | 품질 점수와 계보 연결 | 품질 규칙 적용률 90% 이상 |
| 5 | 검색, 승인, 사용 로그 기록 | 검색 클릭률, 승인 리드타임 |

> 요약: 카탈로그는 자동 수집과 사람의 의미 보완을 결합해 검색 가능한 신뢰 자산으로 전환함.

## Ⅳ. 특징

| 구분 | 문서/위키 방식 | 데이터 카탈로그 | 판단 포인트 |
|:---|:---|:---|:---|
| 갱신 | 수동 작성 | 스키마 자동 수집 | stale metadata 5% 이하 |
| 의미 | 자유 텍스트 | 업무 용어집 연결 | 용어 중복률 |
| 통제 | 문서 열람 | 권한 승인/감사 연계 | 승인 SLA 2일 이하 |
| 한계 | 구축 부담 작음 | 스튜어드 운영 필요 | owner 지정률 100% |

> 요약: 카탈로그는 자동 수집만으로 완성되지 않고 업무 의미와 소유자 관리가 함께 필요함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 엑셀 목록, 위키 | 메타데이터 저장소+검색 | 자산 300개 이상 |
| 비용/처리 | 수동 갱신 | 자동 스캔+스튜어드 검토 | 월 변경 50건 이상 |
| 운영/위험 | 설명 노후화 | 최신성 지표 관리 | 스키마 변경 빈도 |

> 요약: 자산 수와 변경 빈도가 커질수록 자동 수집형 카탈로그가 필요함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 설명 부정확 | owner 미지정 | 도메인별 steward 지정 | owner 누락 0건 |
| 검색 실패 | 용어 불일치 | 업무 용어집, 동의어 사전 | 검색 성공률 80% 이상 |
| 민감정보 노출 | PII 태그 누락 | 정규식+ML 탐지, 승인 워크플로 | PII 미분류 0건 |

> 요약: 카탈로그 리스크는 의미 품질과 민감정보 태깅에서 발생하므로 steward와 자동 탐지를 병행함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 등록 | 핵심 자산 등록률 95% 이상 | 커넥터 스캔 리포트 |
| 최신성 | 메타데이터 지연 24시간 이하 | last scan timestamp |
| 활용 | 월간 활성 사용자 60% 이상 | 검색/조회 로그 |

> 요약: 카탈로그 성과는 등록률, 최신성, 활용 로그로 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 자산 수집: DW, Lake, BI, Kafka Schema Registry를 커넥터로 연결하고 핵심 자산 등록률 95% 이상 달성
2. 의미 표준화: 고객, 상품, 주문 등 핵심 용어 100개를 glossary로 정의하고 owner, steward 필수값 적용
3. 통제 연계: PII 태그 기반 승인 워크플로와 감사로그를 SSO/RBAC에 연결해 승인 리드타임 2일 이하 관리

**결론 (2줄):**
- 기술사 판단: 카탈로그는 도구 도입보다 owner, glossary, 품질 점수, 권한 승인 체계를 먼저 정해야 함
- 향후 방향: AI 기반 자동 태깅, 자연어 검색, 데이터 계약 검증과 연결되어 데이터 운영의 진입점이 됨
