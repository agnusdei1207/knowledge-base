## 핵심 인사이트 (3줄 요약)
- 10만 개의 알 수 없는 파일이 굴러다니는 데이터 레이크(Data Lake)를 거대한 쓰레기장(Data Swamp)이 되지 않도록 지켜주는 **전사 데이터의 백과사전이자 내비게이션 시스템**.
- 이 데이터가 언제, 누구에 의해 만들어졌고, 어떤 컬럼을 가지고 있으며, 개인정보(PII)가 포함되어 있는지를 적어두는 **'메타데이터(Metadata)의 중앙 저장소'** 역할을 함.
- 단순히 수동으로 기록하는 것을 넘어, 최근에는 머신러닝을 이용해 새 파일이 들어오면 스스로 메타데이터를 추출하고 태그를 붙이는 자동화된 '활성(Active) 데이터 카탈로그'로 진화 중임.

## Ⅰ. 개요 및 필요성
- **개요**: 조직 내에 분산된 데이터 자산을 메타데이터를 통해 체계적으로 정리, 검색, 평가, 접근할 수 있도록 돕는 중앙 집중식 인벤토리 시스템.
- **필요성**: 신입 데이터 분석가가 "어제 가입한 20대 여성 통계"를 내려고 S3에 접속함. `user_data_2023_final_v2_real_final.csv`라는 파일을 발견했지만, 이게 진짜인지 테스트 파일인지 알 길이 없어 선배를 찾아다니며 3일을 허비함. "데이터를 찾는 데 80%의 시간을 쓰는 바보짓을 끝내고, 구글 검색창처럼 사내 데이터를 1초 만에 찾을 순 없을까?"라는 고통에서 출발함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **1. 메타데이터 수집 (Crawling & Harvesting)**:
  - RDB, S3, 하둡 등 전사 데이터 소스에 크롤러(Crawler)를 봇처럼 파견함.
  - 테이블 명, 컬럼 타입, 로우 개수, 마지막 업데이트 시간(Technical Metadata)을 자동으로 긁어옴.
- **2. 비즈니스 용어집 (Business Glossary)**:
  - 기술적 컬럼명(`usr_reg_dt`)을 비즈니스 용어(`회원 가입 일자`)로 매핑하여 비개발자(경영진)도 쉽게 검색할 수 있도록 연결함. (비즈니스 메타데이터).
- **3. 데이터 거버넌스 및 검색 (Search & Governance)**:
  - 검색창에 `VIP 고객`을 치면 관련 테이블들이 쭉 나오고, 해당 테이블의 신뢰도 별점(⭐ 4.5), 소유자(마케팅 김대리), 개인정보 포함 여부(마스킹 필요)가 한눈에 보임.

```text
[ 데이터 카탈로그 도입 전/후의 데이터 탐색 과정 ]

 🙈 [ 도입 전: 원시 시대 ]
 분석가: "VIP 매출 데이터 어디 있어요?" 
 ➡️ 슬랙(Slack)으로 3개 부서에 물어봄 ➡️ 3일 뒤 S3 구석에서 파일 발견 ➡️ 근데 컬럼 뜻을 몰라서 또 물어봄 ➡️ 1주일 허비.

 🔎 [ 도입 후: 데이터 구글링 ]
 분석가: (카탈로그 검색창에 'VIP 매출' 입력) 
 ➡️ 0.1초 만에 `gold_vip_sales` 테이블 검색됨!
 ➡️ 꼬리표(태그): "소유자: 재무팀 / 신뢰도 최상 / 어제 밤 12시 업데이트됨"
 ➡️ 클릭 한 번으로 바로 분석 시작! (탐색 시간 99% 단축)
```

## Ⅲ. 비교 및 연결
| 구분 | 데이터 딕셔너리 (Data Dictionary) | 데이터 카탈로그 (Data Catalog) |
|---|---|---|
| **범위** | 단일 DB 내의 컬럼과 테이블 설명 | **전사(모든 DB, 레이크) 데이터 자산의 통합** |
| **타겟 사용자** | DBA, 데이터 엔지니어 (기술자) | **모든 임직원 (분석가, 마케터, 경영진)** |
| **생성 방식** | 주로 수동 작성 (명세서) | **크롤러와 AI를 통한 자동 수집 (Auto-Discovery)** |
| **추가 기능** | 컬럼 타입, 제약조건 명시 | **데이터 리니지(족보), 협업(댓글/별점), 권한 통제** |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **크롤링 병목과 활성 카탈로그 (Active Catalog)**: 실무에서 카탈로그 크롤러를 매일 자정에 돌리면 데이터 갱신이 하루씩 지연됨. 최신 아키텍처(Data Fabric)는 데이터 파이프라인(Airflow 등)이 돌 때마다 성공/실패 여부와 메타데이터를 실시간 API로 카탈로그에 쏘도록(Push) 연동하여, 항상 최신 상태를 유지하는 Active Catalog 방식을 채택해야 함. (대표 솔루션: AWS Glue Data Catalog, Amundsen, Collibra).
- **개인정보 보호(PII)와 자동 마스킹**: 기술사는 카탈로그에 AI 분류기를 달아서, 새로 들어온 파일에 '주민번호' 패턴이 보이면 즉시 **[PII 민감 정보] 태그**를 자동으로 붙이고 일반 직원의 조회를 차단(마스킹)하는 컴플라이언스(보안) 파이프라인을 구축해야 함.
---
## Ⅴ. 기대효과 및 결론
- "데이터를 모아두면 알아서 쓰겠지"라는 방관적 태도를 버리고, 전사 임직원이 데이터를 쉽게 쇼핑(Shopping)할 수 있는 '데이터 민주화(Data Democratization)'의 핵심 포털임.
- 데이터 레이크가 '거대한 창고'라면 데이터 카탈로그는 그 창고의 '완벽한 재고 목록'이며, 이게 없으면 창고 안의 데이터는 평생 햇빛을 보지 못하는 썩은 쓰레기가 됨.

1. 엄청나게 큰 도서관(데이터 레이크)을 지었는데, 책들마다 '제목'이 안 적혀있어서 사람들이 무슨 책인지 몰라 아무도 안 읽었어요.
2. **데이터 카탈로그**는 도서관 입구에 있는 '최첨단 도서 검색용 컴퓨터'예요!
3. 이 컴퓨터에는 "이 책은 요리책이고, 10페이지에 케이크 레시피가 있고, 어제 새로 들어왔어"라는 정보(메타데이터)가 완벽하게 적혀 있어서 누구나 1초 만에 원하는 책을 찾을 수 있답니다!
