# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 카탈로그를 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 카탈로그는 데이터 자산의 **위치·스키마·소유자·품질·사용 이력**을 하나로 모아 **검색 가능한 메타데이터 저장소**로 만드는 관리 체계다.
- **왜 필요한가**: 테이블·파일·API가 수천 개로 늘면 이름만 봐서는 최신 버전이 뭔지, 누가 승인권자인지, 어떤 컬럼이 개인정보인지 알 수 없다. 카탈로그는 이 탐색·승인 시간을 줄인다.
- **핵심 직관**: 도서관 검색 시스템처럼 제목·저자·분류·대출 이력·이용 규칙을 붙여 자산을 찾게 해주는 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 메타데이터 관리 체계 | 데이터 카탈로그가 속하는 상위 개념 — 데이터에 대한 데이터를 조직적으로 다루는 체계 | 도서관 사서 업무 전체 |
| 기술 메타데이터 | 스키마·컬럼 타입·파일 크기 등 시스템이 자동 수집하는 정보 | 책의 ISBN·쪽수 |
| 업무 메타데이터 | 비즈니스 용어·설명·도메인 분류 — 사람이 채우는 의미 정보 | 책의 줄거리·장르 |
| 운영 메타데이터 | 접근 이력·갱신 주기·계보·품질 점수 — 사용 중 자동 생성되는 정보 | 대출 이력·인기도 |
| 업무 용어집(Business Glossary) | 업무 용어와 실제 기술 자산(테이블·컬럼)을 매핑하는 사전 | 색인 카드 목록 |
| 데이터 스튜어드(Data Steward) | 자산 설명·소유자 지정을 관리하는 담당자 | 담당 사서 |
| 데이터 계보(Lineage) | 자산이 어디서 생성되어 어떻게 변환·소비됐는지 추적하는 정보 | 책의 개정판 이력 |
| 품질 점수(Quality Score) | 완전성·정확성·일관성 등을 수치로 나타낸 지표 | 도서 상태 등급 |

## 깊이 이해

### 배경 — tribal knowledge 문제
- 데이터 웨어하우스·레이크에 테이블이 수천 개 쌓이면 "이 테이블이 최신인지, 신뢰할 수 있는지"를 아는 사람이 그 테이블을 만든 소수(tribal knowledge)에 갇힌다. 그 사람이 퇴사하면 지식도 함께 사라진다. 카탈로그는 이 암묵지를 메타데이터로 명시화한다.

### 작동 원리 — 커넥터부터 사용 이력까지
- 커넥터가 DB·파일 저장소·BI 도구의 스키마를 주기적으로 스캔해 기술 메타데이터를 자동 수집한다.
- 사용자는 업무 용어(예: "고객")나 태그로 검색하고, 스튜어드가 설명·소유자·분류를 채워 업무 메타데이터를 보완한다.
- 품질 규칙과 사용 로그는 파이프라인·BI 조회 이력에서 자동으로 갱신되어 운영 메타데이터가 된다.

### 3종 메타데이터가 결합된 실제 예시
- `customer_mart` 테이블: 기술 메타데이터로 컬럼 25개·타입·파티션 키가 자동 수집되고, 업무 메타데이터로 owner(고객팀)·설명·"고객" 용어와의 매핑이 등록되며, 운영 메타데이터로 refresh 06:00 완료·PII 컬럼 3개 태깅·품질 점수 97점·이 테이블을 쓰는 상위 대시보드 12개가 표시된다. 이 세 가지가 한 화면에 모이면 사용자가 "이 테이블을 써도 되는지" 스스로 판단할 수 있다.

### 카탈로그 vs 위키 — 무엇이 다른가 (판별원리)
- 자산이 300개를 넘고 스키마 변경이 월 50건 이상이면 수동 위키 문서는 갱신을 못 따라가 며칠 만에 오래된 정보가 된다. 카탈로그는 커넥터가 스키마를 자동 재스캔해 최신성을 유지하므로, 자산 수·변경 빈도가 일정 규모를 넘으면 자동 수집형 카탈로그가 필수가 된다.
- 반대로 자산이 수십 개뿐이면 위키만으로도 충분할 수 있다 — 자동 수집·승인 워크플로를 유지하는 비용이 오히려 더 클 수 있기 때문이다.

### 비유와 흔한 오해
- **비유**: 마트의 상품 라벨(원산지·유통기한)과 재고 시스템(위치·수량)을 합친 것 — 상품이 어디 있는지뿐 아니라 언제 만들어졌고 담당자가 누구인지도 함께 보여준다.
- **오해**: 카탈로그는 그냥 문서 저장소가 아니다. 자동 수집·승인 흐름·품질 점수·사용 로그가 없으면 아무도 안 믿는 "오래된 설명 저장소"로 전락한다 — 이 지점이 위키와의 본질적 차이다.

## 연결 개념
- 데이터 거버넌스: 카탈로그가 수집한 메타데이터에 소유자·승인·정책 기준을 부여하는 상위 체계
- 데이터 패브릭: 카탈로그를 핵심 구성요소로 삼아 메타데이터 자동화·접근 경로 선택까지 확장한 상위 아키텍처
- 데이터 품질 관리: 카탈로그의 품질 점수가 근거로 삼는 완전성·정확성·일관성 측정 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 카탈로그 답안은 검색 도구 소개가 아니라 메타데이터 자동 수집, 업무 의미, 소유권, 품질, 접근 통제의 운영 구조로 작성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 카탈로그는 데이터 자산의 기술/업무/운영 메타데이터를 통합해 탐색과 재사용을 지원하는 관리 체계임.
> 2. **가치**: 데이터 탐색 시간을 시간 단위에서 분 단위로 줄이고, 승인 이력과 품질 점수로 오사용을 통제함.
> 3. **판단 포인트**: 자동 수집 범위, 업무 용어 표준화, 스튜어드 운영, 권한 연계를 함께 설계해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 데이터 카탈로그는 데이터 자산 메타데이터 관리 체계임.
- 배경: 테이블, 파일, API, 리포트가 증가하면 의미 중복과 오사용이 발생한다.
- 필요성: 자산 위치, 의미, 소유자, 품질, 계보를 함께 관리해 데이터 재사용 기준을 제공한다.

---

## Ⅱ. 구조 및 구성요소

```text
Data Source -> Metadata Connector -> Catalog Repository -> Search/Glossary -> Approval/Access
                                      +-> Quality Score
                                      +-> Usage Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 커넥터 | DB, Lake, BI, API 메타데이터 수집 | JDBC, REST, object storage |
| 저장소 | 스키마, 태그, 설명, owner 보관 | OpenMetadata, DataHub |
| 검색/용어집 | 업무 용어와 데이터 자산 연결 | synonym, domain, glossary |
| 접근 승인 | 사용 신청, 승인, 감사로그 연결 | SSO, RBAC 연계 |

> 요약: 데이터 카탈로그는 커넥터, 저장소, 검색, 승인 흐름이 결합될 때 운영 체계가 됨.

## Ⅲ. 동작원리 및 흐름도

```text
자산 스캔 -> 메타데이터 적재 -> 태그/용어 매핑 -> 품질/계보 연결 -> 검색/승인/사용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 소스 시스템 스캔 | 자산 등록률 95% 이상 |
| 2 | 스키마와 샘플 통계 적재 | 수집 지연 24시간 이하 |
| 3 | 업무 용어, PII 태그, owner 매핑 | owner 누락 0건 |
| 4 | 품질 점수와 계보 연결 | 품질 규칙 적용률 90% 이상 |
| 5 | 검색, 승인, 사용 로그 기록 | 검색 클릭률, 승인 리드타임 |

> 요약: 카탈로그는 자동 수집과 사람의 의미 보완을 결합해 검색 가능한 신뢰 자산으로 전환함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|

| 최신성 | 메타데이터 지연 24시간 이하 | last scan timestamp |
| 활용 | 월간 활성 사용자 60% 이상 | 검색/조회 로그 |

> 요약: 카탈로그 성과는 등록률, 최신성, 활용 로그로 검증함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 - 단계별 또는 항목별):**
1. 자산 수집: DW, Lake, BI, Kafka Schema Registry를 커넥터로 연결하고 핵심 자산 등록률 95% 이상 달성
2. 의미 표준화: 고객, 상품, 주문 등 핵심 용어 100개를 glossary로 정의하고 owner, steward 필수값 적용
3. 통제 연계: PII 태그 기반 승인 워크플로와 감사로그를 SSO/RBAC에 연결해 승인 리드타임 2일 이하 관리

**결론 (2줄):**
- 기술사 판단: 카탈로그는 도구 도입보다 owner, glossary, 품질 점수, 권한 승인 체계를 먼저 정해야 함
- 향후 방향: AI 기반 자동 태깅, 자연어 검색, 데이터 계약 검증과 연결되어 데이터 운영의 진입점이 됨
