## 미리 알고가기

- 인메모리 DB는 주 데이터를 메모리에 두고 디스크 접근을 줄이는 데이터베이스 계열임
- TTL(Time To Live)은 키가 자동 삭제될 때까지의 유효 시간임
- RDB는 시점별 스냅샷, AOF(Append Only File)는 변경 명령 로그로 재시작 데이터를 복구함
- Sentinel은 주 복제본 장애를 감지해 승격하고, Redis Cluster는 해시 슬롯으로 키를 여러 노드에 분산함
- 제거 정책(Eviction Policy)은 메모리 한도에 도달했을 때 삭제할 키를 결정함

## 작성 근거(검토용)

- Redis는 자료형·원자 연산·TTL·제거 정책·영속성·복제·클러스터를 핵심 축으로 설명함
- 비교표는 Memcached와 데이터 모델·복구·장애 조치·분산·서버 연산 차이를 대비함
- 실무 사례는 API 캐시와 세션 저장소에서 동시 만료·데이터 손실 구간·장애 조치 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: Redis는 메모리의 키-자료구조에 원자 명령을 수행하고 TTL·영속성·복제·클러스터 기능을 제공하는 인메모리 데이터베이스임
- **배경/필요성**: 세션·캐시·실시간 순위처럼 반복 조회와 원자 갱신이 많은 데이터를 낮은 지연으로 처리하기 위해 메모리 중심 저장·복구 구조가 필요함

## Ⅱ. 특징

- 문자열·해시·리스트·집합·정렬 집합·스트림에 자료형별 원자 명령을 수행함
- TTL과 제거 정책으로 키 수명을 관리하지만 동시 만료와 제거 급증이 원본 저장소 부하로 이어질 수 있음
- RDB·AOF의 기록 주기에 따라 쓰기 비용과 장애 후 데이터 손실 구간이 달라짐
- 복제·Sentinel·Cluster로 장애 조치와 수평 분산을 구성하며 다중 키 연산은 슬롯 배치 제약을 받음

## Ⅲ. 종류 및 비교

| 판단 기준 | Redis | Memcached |
|:---|:---|:---|
| 데이터 모델 | 문자열·해시·집합·정렬 집합·스트림 등 | 바이트 문자열 기반 단순 키-값 |
| 서버 연산 | 자료형별 원자 명령·트랜잭션·Lua 스크립트 | 조회·저장·증감 등 제한된 캐시 명령 |
| 영속성 | RDB 스냅샷과 AOF 로그 선택 | 자체 영속성 없음 |
| 장애 조치 | 복제와 Sentinel로 주 복제본 승격 | 클라이언트가 장애 노드 제외·재배치를 처리 |
| 수평 분산 | Redis Cluster의 해시 슬롯으로 샤딩 | 클라이언트 해싱으로 서버를 분산 선택 |
| 적합 조건 | 세션·순위·스트림처럼 자료형 연산과 복구가 필요한 데이터 | 영속성 없이 단순 객체 캐시가 필요한 데이터 |

> 요약: Redis는 자료형 연산·영속성·복제·클러스터를 제공하고, Memcached는 단순 키-값 캐시에 집중함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 키 공간·자료구조 | 키에 문자열·해시·리스트·집합·스트림 값을 연결하고 원자 명령을 수행함 |
| TTL·제거 정책 | 키 만료 시점과 메모리 한도 도달 시 삭제 대상을 결정함 |
| RDB·AOF | 스냅샷 또는 변경 로그로 재시작 후 복구할 데이터 범위를 정함 |
| 복제·Sentinel | 주 복제본 변경을 복제하고 장애 감지·승격을 수행함 |
| Redis Cluster | 해시 슬롯을 노드에 배치하고 키 요청을 담당 노드로 전달함 |

```text
클라이언트 -> 해시 슬롯 -> 키·자료구조 명령
                         |
              TTL·제거 / RDB·AOF / 복제
```

> 요약: 클러스터가 키의 담당 노드를 정하고 자료구조 명령 결과를 TTL·영속성·복제 계층에 반영함.

## Ⅴ. 원리 및 절차 흐름도

```text
명령 수신 -> 키·슬롯 확인 -> 원자 명령 실행 -> 영속성·복제 반영 -> 응답
```

1. **명령 수신**: 서버가 클라이언트의 키와 자료형 명령을 수신함
2. **키·슬롯 확인**: Cluster는 키의 해시 슬롯을 계산해 담당 노드 여부를 판정함
3. **원자 명령 실행**: 담당 노드가 메모리 자료구조와 TTL 정보를 갱신함
4. **영속성·복제 반영**: 설정에 따라 AOF에 기록하고 보조 복제본으로 명령을 전파함
5. **결과 반환**: 명령 결과 또는 다른 담당 노드 정보를 클라이언트에 반환함

> 요약: Redis는 키의 담당 노드에서 원자 명령을 수행하고 설정된 AOF·복제 경로에 변경을 반영함.

## Ⅵ. 실무 사례

1. API 응답 캐시는 TTL 분산과 단일 요청 병합을 적용하고 캐시 적중률·동시 만료 키 수를 확인함
2. 세션 저장소는 AOF와 Sentinel을 적용하고 장애 시 데이터 손실 구간·주 복제본 승격 시간을 확인함

## Ⅶ. 결론

- Redis는 자료형 연산·키 수명·복구 허용 구간·장애 조치와 해시 슬롯 제약을 기준으로 적용해야 함
