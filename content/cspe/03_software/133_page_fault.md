## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 참조하려는 페이지가 현재 물리 메모리에 없어 트랩(Trap)이 발생하는 현상 |
| 배경 | Demand Paging 기법에서 필요한 시점에만 페이지를 로드함에 따라 발생 |
| 출제 의도 | OS의 예외 처리 루틴 및 디스크 I/O와의 상호작용 프로세스 이해 |

## Ⅱ. 구성요소
```text
[ Page Table Entry ]
+-------+-------+-------+
| P-Num | V-Bit | Frame |  (V-Bit=0: Page Fault)
+-------+-------+-------+
       |
       v
+--------------+    +--------------+    +--------------+
|   CPU Trap   | -> | OS Handler   | -> | Disk I/O     |
+--------------+    +--------------+    +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 유효 비트 (V-Bit) | 페이지가 메모리에 있는지(1) 없는지(0) 표시 | 재고 유무 태그 |
| Fault 핸들러 | 부재 발생 시 실행되는 커널 내 예외 처리 함수 | 품절 대응 매뉴얼 |
| 스왑 영역 | 메모리에서 쫓겨난 페이지가 저장되는 디스크 공간 | 외부 창고 |
> 요약: 유효 비트가 0일 때 하드웨어 트랩이 발생하여 OS가 개입함.

## Ⅲ. 절차
```text
Reference -> V-bit 0 -> Trap OS -> Save State -> Find Page on Disk
      ^                                              |
      +----- Update Page Table <---- Bring Page <----+
```
1. 참조 및 부재 확인: CPU가 메모리 접근 시 Page Table의 Valid bit가 0임을 감지.
2. 운영체제 제어권 획득: OS로 트랩 발생, 현재 프로세스 상태 저장.
3. 디스크 읽기 요청: 백업 저장장치(Disk)에서 해당 페이지 위치를 찾아 로드 시작.
4. 테이블 갱신 및 재개: 페이지를 메모리에 적재 후 V-bit를 1로 변경, 명령 재실행.
> 요약: 디스크 I/O가 포함되어 성능에 큰 영향을 미치므로 최소화가 관건임.

## Ⅳ. 문제점
- 빈번한 Page Fault는 시스템 성능을 급격히 저하시키는 스래싱 유발.
- 페이지 교체 알고리즘(FIFO 등)의 비효율성으로 인한 벨레이디의 모순 발생.

## Ⅴ. 개선방안
- 참조 국부성(Locality)을 고려한 LRU 등 최적 교체 알고리즘 적용.
- 프리페칭(Prefetching) 및 클러스터링을 통해 향후 필요 페이지 미리 적재.

## Ⅵ. 전망
- NVMe SSD 확산: 스왑 장치 속도 향상으로 Page Fault 처리 지연 대폭 감소.
- 예측 기반 로딩: AI 모델을 활용하여 다음에 참조될 페이지를 실시간 예측 및 로드.
