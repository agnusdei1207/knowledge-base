# 📖 【암기용】 개념 완전 이해

> 목적: COCOMO를 LOC 기반 비용 모델과 비용 동인 조정 방식으로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: COCOMO는 소프트웨어 규모와 비용 동인으로 공수·기간을 추정하는 경험적 모델
- **왜 필요한가**: 프로젝트 초기에 일정과 인력 규모를 수치로 제시해야 하며, 단순 전문가 감에만 의존하면 과소추정이 발생한다.
- **핵심 직관**: 같은 면적의 건물도 지반·층수·마감재에 따라 비용이 달라지듯, 같은 LOC도 난이도와 팀 역량에 따라 공수가 달라진다.

## 깊이 이해
- **배경·문제의식**: Boehm의 COCOMO는 과거 프로젝트 데이터를 기반으로 KLOC와 비용 동인으로 개발 공수를 추정하기 위해 제안됨.
- **작동 원리**: Basic은 규모만 사용하고, Intermediate는 제품·컴퓨터·인력·프로젝트 비용 동인을 곱하며, Detailed는 단계별 비용 동인을 반영함.
- **비유**: 택시요금이 거리만이 아니라 심야·정체·고속도로 요금을 반영하는 것과 같은 추정 방식임.
- **구체 예시**: 50 KLOC 업무시스템을 Semi-detached로 보고 EAF 1.2를 적용하면 기본 공수에 복잡도와 팀 조건을 반영함.
- **흔한 오해·주의점**: COCOMO는 현대 애자일·노코드·생성형 AI 환경에 그대로 맞지 않으므로 보정계수와 실적 데이터 캘리브레이션이 필요함.

## 연결 개념
- SW Cost Estimation: 비용 산정 모델 선택
- Function Point: LOC 이전 단계 규모 산정 대안
- 과소추정 리스크: 일정 지연과 품질 저하의 주요 원인

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: COCOMO 답안은 모델 단계, 개발 유형, 비용 동인, 현대 적용 한계를 함께 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: COCOMO는 KLOC와 비용 동인(EAF)을 이용해 노력(PM), 기간(TDEV), 인력(People)을 추정하는 경험 기반 비용 모델이다.
> 2. **가치**: Basic, Intermediate, Detailed 단계를 통해 초기 견적부터 상세 단계별 견적까지 산정 근거를 체계화한다.
> 3. **판단 포인트**: LOC 예측 오차와 비용 동인 주관성을 줄이기 위해 FP 변환, 실적 데이터 보정, 민감도 분석이 필요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 비용 산정 모델 이해 확인 | Organic·Semi-detached·Embedded, PM, TDEV | 단순 LOC 계산식만 쓰고 비용 동인을 누락하지 않음 |
| 적용 한계 판단 확인 | EAF, 보정계수, 실적 기반 캘리브레이션 | 현대 개발 환경에 무조건 적용한다고 단정하지 않음 |
| FP·공공 대가산정 비교 확인 | LOC 기반 vs 기능 기반 | FP와 COCOMO 목적을 혼동하지 않음 |
> 요약: COCOMO 문제는 수식보다 규모, 난이도, 비용 동인을 결합해 견적 신뢰도를 높이는 설명이 필요하다.

---

## Ⅰ. 개요 및 필요성

COCOMO는 LOC와 비용 동인 기반 SW 공수 산정 모델이다.
프로젝트 초기에는 일정·인력·예산을 수치로 제시해야 하나, 경험식만으로는 과소추정과 일정 지연이 발생한다.
COCOMO는 규모와 비용 동인을 분리해 추정하므로 견적 근거와 민감도 분석을 제시할 수 있다.

---

## Ⅱ. 구조 및 구성요소

```text
규모 추정(KLOC) -> 개발 유형 선택 -> 비용 동인 평가
Basic/Intermediate/Detailed -> PM 산정 -> TDEV 산정
PM/TDEV -> 평균 인력 -> 일정·예산 계획
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| KLOC | 규모 입력 | FP-LOC 변환 또는 유사 프로젝트 LOC |
| 개발 유형 | 난이도 분류 | Organic, Semi-detached, Embedded |
| 비용 동인 | 노력 조정 | 제품·플랫폼·인력·프로젝트 요인 |
| 산출값 | 계획 기준 | PM, TDEV, 평균 투입인력 |
> 요약: COCOMO는 규모, 개발 유형, 비용 동인을 결합해 공수와 기간을 산출한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
요구사항/설계 -> KLOC 추정 -> 개발 유형 판정
-> Basic PM 계산 -> 비용 동인 EAF 적용
-> TDEV 계산 -> 인력·예산 배분 -> 실적 보정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | KLOC 또는 FP-LOC 변환값 산정 | 유사 프로젝트 대비 편차 20% 이하 |
| 2 | Organic·Semi-detached·Embedded 분류 | 팀 경험·제약·복잡도 근거 |
| 3 | 비용 동인 등급 평가 | EAF 산정 근거 100% 첨부 |
| 4 | PM·TDEV·평균 인력 계산 | 계산식 재현 가능 |
| 5 | 실적 데이터로 보정 | 완료 프로젝트 MRE 25% 이하 |
> 요약: COCOMO는 최초 계산보다 비용 동인 평가와 실적 기반 보정으로 견적 오차를 줄이는 절차가 핵심이다.

## Ⅳ. 특징

| 구분 | 단순 경험 견적 | COCOMO | 수치·판단 기준 |
|:---|:---|:---|:---|
| 산정 기준 | 담당자 경험 | KLOC와 비용 동인 | PM, TDEV 산출 |
| 난이도 반영 | 정성 판단 | Organic 등 3유형 | 제약·복잡도 기준 |
| 조정 방식 | 회의 보정 | EAF 곱셈 | 15개 이상 비용 동인 |
| 한계 | 근거 부족 | LOC 추정 선행 필요 | 초기 LOC 오차 20% 관리 |
> 요약: COCOMO는 비용 동인을 수치화하지만 LOC 추정 오차와 조직별 생산성 차이를 보정해야 한다.

| 비용 동인 주관성 | 평가 기준 불명확 | 등급 기준표와 독립 검토 | EAF 재검토 항목 수 |

> 요약: COCOMO 리스크는 규모 오차, 동인 평가, 조직 보정, 일정 압축을 따로 통제해야 한다.

| 동인 근거 | EAF 항목 근거 100% | 비용 동인 평가표 |

| 보정 체계 | 완료 프로젝트 10건 이상 축적 | 견적 데이터베이스 |
> 요약: COCOMO 적용 성패는 수식보다 실적 데이터 축적과 추정 오차 관리로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 요구사항 단계 FP를 언어별 LOC 환산표로 변환하고 KLOC 범위를 낙관·기준·비관 3점으로 산정함.
2. 제품 복잡도, 플랫폼 제약, 인력 경험, 도구 성숙도 비용 동인을 평가해 EAF 근거표를 작성함.
3. 완료 프로젝트의 계획 PM·실적 PM·MRE를 축적하고 분기별로 COCOMO 계수를 보정함.

**결론 (2줄):**
- 기술사 판단: LOC 예측 가능성과 실적 데이터가 있으면 COCOMO를 쓰고, 요구사항 단계 공공 대가산정은 FP를 우선 적용함.
- 향후 방향: COCOMO는 DevOps·AI 코드 생성 생산성 데이터를 반영한 조직별 보정 모델로 운영되어야 함.
