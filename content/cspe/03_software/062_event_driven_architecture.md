## Ⅰ. 개요
- 정의: 시스템 상태 변화(이벤트)를 감지하고 이에 반응하는 방식으로 동작하는 아키텍처.
- 출제 의도: 서비스 간 비동기 결합을 통한 확장성 확보 및 실시간 대응 체계 구축 역량 평가.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Event Producer ] --(Fire)--> [ Event Channel ] --(Route)--> [ Event Consumer ]
   (Action Occurred)              (Bus/Broker)                 (Reactive Logic)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 이벤트 (Event) | 과거에 발생한 '사실'을 담은 데이터 패킷 | 알림 메시지 |
| 이벤트 버스 | 이벤트를 전송하고 라우팅하는 중앙 통로 | 고속도로/우체국 |
| 컨슈머 | 수신된 이벤트를 처리하거나 다른 이벤트를 파생함 | 행동 대원 |
> 요약: 발행자는 누가 소비하는지 몰라도 되며(Decoupling), 소비자도 독립적임.

## Ⅲ. 절차
- ASCII 흐름도
  [사건 발생] -> [이벤트 생성/발행] -> [필터링/라우팅] -> [병렬 처리/응답]
- 4단계 설명
1. 비즈니스 도메인 내에서 의미 있는 변화(주문 완료 등)가 발생함.
2. 발생 주체가 이벤트를 생성하여 중앙 이벤트 채널로 비동기 전송함.
3. 채널은 구독 정보를 확인하여 관심 있는 모든 서비스에 이벤트를 전파함.
4. 각 서비스는 자신의 비즈니스 로직에 맞춰 이벤트를 소화함.
> 요약: 요청-응답(Request-Response)의 대기 시간을 없앤 반응형 흐름임.

## Ⅳ. 문제점
- 흐름 추적 어려움: 요청이 어디서 시작되어 어떻게 끝나는지 전역적인 흐름 파악 힘듬.
- 정합성 보장: 비동기 처리 특성상 실시간 데이터 일치(ACID) 보장이 매우 어려움.

## Ⅴ. 개선방안
- 분산 트레이싱: Trace ID를 이벤트 헤더에 실어 서비스 간 흐름 가시성 확보함.
- 멱등성 설계: 동일 이벤트가 여러 번 수신되어도 결과가 같도록 처리 로직 고도화함.

## Ⅵ. 전망
- 서버리스(Serverless) 기술과 결합하여 완벽한 'Event-driven Cloud' 환경으로 진화함.
- AI 모델이 이벤트를 실시간 분석하여 다음 행동을 결정하는 'Intelligent EDA' 확산됨.
- 기업 내 모든 데이터를 이벤트 스트림으로 취급하는 'Data Mesh' 전략의 근간 기술이 됨.
