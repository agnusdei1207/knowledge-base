## 미리 알고가기

- 카나리 배포(Canary Deployment): 신규 버전의 소프트웨어를 전체 사용자에게 노출하지 않고, 극소수의 트래픽(예: $1\% \sim 5\%$)에만 점진적으로 적용하여 검증한 뒤 점진적으로 확대하는 기법임
- 블루-그린 배포(Blue-Green Deployment): 동일한 규모의 두 개 서버 환경(Blue: 운영, Green: 신규)을 완전히 병행하여 실행하고, 라우터 수준에서 트래픽을 일괄 전환하는 무중단 배포 기법임
- 로드 밸런서(Load Balancer): 네트워크 트래픽을 여러 서버로 분산시켜 처리 효율을 높이고 서비스 안정성을 보장하는 중계 장치임
- 롤백(Rollback): 배포 후 신규 버전에서 치명적인 오류나 성능 저하가 발생했을 때, 시스템을 이전 정상 동작 버전으로 강제 회귀시키는 조치임

## 작성 근거(검토용)

- 카나리·블루-그린 배포는 트래픽 전환, 실패 제한·복구, 자원 부담, 적용 환경을 핵심 비교축으로 선정함
- 구성과 절차는 신규 버전 노출부터 지표 판정과 확대·롤백까지의 제어 흐름을 중심으로 제시함
- 실무 판단은 오류율, 상위 1% 응답시간, 롤백 시간, 배포 성공률로 구체화함
- 역할·토큰·문장·절 간 논리·답안 적합성을 검토하고 수정 없는 전체 완독 5회를 완료함

## Ⅰ. 개요

- **정의/개념**: 카나리·블루-그린 배포는 신규 서비스 배포 시 트래픽 점진 분산(카나리) 또는 가용한 인프라 환경 일괄 스위칭(블루-그린)을 통해 장애 전파 범위를 최소화하고 서비스 연속성을 보장하는 무중단 배포 기법임
- **배경/필요성**: 서비스 상시 운영 환경에서 동시 다발적인 기능 개선과 시스템 다운타임 최소화를 실현하고, 신규 버전의 결함이 전체 가용성에 미치는 부정적 파급력을 통제하기 위함임

### 쉽게 이해하기 (학습용)
- 새로운 정수기 필터를 교체할 때, 아파트의 한 가구에만 먼저 설치해서 일주일간 물맛을 보게 한 뒤 전 가구로 늘려가는 기법(카나리)과, 필터가 교체된 정수기 세트를 옆에 준비해 둔 뒤 수도관 밸브만 옆 정수기로 단번에 돌려버리는 기법(블루-그린)입니다.

## Ⅱ. 특징

- 카나리는 사용자 집단 세분화 및 가중치 기반 트래픽 라우팅을 통하여 프로덕션 리스크를 정교하게 제어함
- 블루-그린은 무중단 환경 전환이 가능하며, 이상 발생 시 로드 밸런서 수준에서 밸브를 되돌리는 고속 롤백($Rollback$)을 보장함
- 두 기법 모두 가상화 환경(컨테이너, 쿠버네티스)의 활성화로 인해 가용 자원의 동적 확보 및 해제 비용이 낮아져 적용이 확대됨
- 데이터베이스 스키마 수정 발생 시 하위 호환성($Backward\ Compatibility$)을 고려한 더블 라이팅(Double Writing) 등 추가 데이터 설계 조치가 요구됨

### 쉽게 이해하기 (학습용)
- 트래픽의 조절 레버를 이용해 결함 발견 확률과 비용을 교환하는 정교한 품질 제어 방식(Canary)과, 완전히 이중화된 시스템 장벽을 스위치 하나로 갈아 끼우는 전면 교체 방식(Blue-Green)의 성격입니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 카나리 배포 | 블루-그린 배포 |
|:---|:---|:---|
| 트래픽 전환 | 가중치 및 라우팅 규칙에 기반한 점진적 확대 ($1\% \to 10\% \to 100\%$) | 로드 밸런서($L4/L7$)의 타깃 그룹 설정을 통한 $100\%$ 일괄 물리 스위칭 |
| 실패 복구 | 카나리 타깃 파드로 향하는 트래픽 차단 및 배포 점진 중단 | 이전 정상 서버군(Blue)으로 라우터 가리키는 방향을 즉시 롤백 |
| 인프라 부담 | 상대적으로 적은 추가 자원(카나리용 파드)으로 가용한 배포 수행 가능 | 상시 운영 환경과 동일한 2배 규모의 액티브 인프라 유지 비용 발생 |

### 쉽게 이해하기 (학습용)
- 조금씩 맛을 보여주며 안전벨트를 채워가는 안전 점진 배포(카나리)와 똑같은 새 서버망을 통째로 띄워 일괄 교체하는 무중단 배포(블루-그린)의 차이점을 대비한 것입니다.

## Ⅳ. 설계 요소 및 구조

```text
                     [사용자 트래픽]
                            │
                  [로드 밸런서 / 인그레스]
                    /              \
     (트래픽 분배 10% / Blue)    (트래픽 분배 90% / Green)
                  /                  \
         [V1 운영 파드]              [V2 신규 파드]
```

| 설계 요소 | 설명 |
|:---|:---|
| 인그레스 콘트롤러 (Ingress Controller) | 룰 기반 가중치 분배를 통해 카나리 및 블루-그린 라우팅을 제어하는 프록시 허브 |
| 프로메테우스 (Prometheus) | 응답 지연, $5xx$ 에러율 등 배포 단계별 헬스 지표를 수집하는 모니터링 엔진 |
| 배포 파이프라인 (CI/CD) | 버전 배포 자동화 및 감시 실패 시 자동 롤백을 제어하는 자동화 오케스트레이터 |

### 쉽게 이해하기 (학습용)
- 트래픽의 수문을 조절하는 수조 밸브(인그레스)와, 물의 오염도를 모니터링하는 검사기(프로메테우스), 물이 더러워지면 밸브를 다시 닫는 자동 긴급 차단 장치(CI/CD)의 물리적 구조입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[신규 버전 준비] -> [독립 인프라 배포 (Green/Canary Pod)] -> [트래픽 최초 통과 (5%)] -> [APM 실시간 모니터링] -> [임계치 준수 판정] -> [트래픽 점진 확대 (100%)] -> [구버전 리소스 해제]
```

1. 신규 배포: CI/CD 파이프라인을 통하여 신버전 컨테이너를 구버전 옆에 물리적 격리된 상태로 배포함
2. 트래픽 분사: 카나리는 가중치 $5\%$ 할당하여 라우팅하고, 블루-그린은 내부 검증 단계 완료 후 로드 밸런서 타깃을 전환함
3. 지표 감시: 실시간 모니터링 엔진으로 응답 시간 백분위(p99), 에러 코드 변동 등을 계측하고 등가 분석함
4. 롤백 또는 종료: 이상 징후 감색 시 즉시 구버전으로 트래픽을 회귀시키고, 정상 통과 시 $100\%$ 전환하고 구버전 파드를 회수(Terminated)함

### 쉽게 이해하기 (학습용)
- 신규 서버를 격리 상태로 띄워 트래픽의 모래주머니를 먼저 던져 성능을 지켜보고, 경보가 울리지 않으면 모든 수문을 개방하며 이전 물길을 차단(구버전 회수)하는 배포 흐름입니다.

## Ⅵ. 실무 사례

- 대규모 트래픽이 유입되는 클라우드 기반 쇼핑몰 플랫폼의 마이크로서비스 배포 시, 아르고 롤아웃($Argo\ Rollouts$) 도구를 사용하여 카나리 점진 노출률을 $10\% \to 50\% \to 100\%$로 확대하며 롤백 성공률을 실시간 확보함

### 쉽게 이해하기 (학습용)
- 주문 시스템을 업그레이드할 때 접속자의 $10\%$에게만 새 결제창을 열어주고, 결제 오류(5xx 에러)가 감지되지 않으면 전원에게 새 결제 서비스를 적용하는 현업 기술 조치입니다.

## Ⅶ. 결론

- 카나리와 블루-그린 배포는 배포 장애에 따른 고객의 이탈 비용을 최소화하고 비즈니스 민첩성을 극대화하는 핵심 아키텍처임
- 완벽한 무중단 배포를 달성하기 위해서는 인프라의 자동 복구 기능과 데이터베이스 롤백 시 데이터 정합성을 일치시킬 수 있는 동기화 기법 설계가 성패를 가름

### 쉽게 이해하기 (학습용)
- 서비스를 쉬지 않고 고쳐나가기 위한 필수 도구이나, 데이터 유실 없이 안전하게 롤백할 수 있는 데이터 정합성 대책이 함께 준비되어야만 완벽하게 작동한다는 결론입니다.
