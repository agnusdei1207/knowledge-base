## 미리 알고가기

- 카나리 배포는 일부 트래픽에만 새 버전을 먼저 노출하는 방식임
- 블루-그린 배포는 두 환경을 준비해 트래픽을 한 번에 전환하는 방식임
- 둘 다 무중단 배포와 빠른 복구를 위한 전략임

## Ⅰ. 개요

- **정의/개념**: 카나리 배포는 새 버전을 제한된 사용자나 트래픽에 점진적으로 노출하며 품질을 확인하는 배포 방식이고, 블루-그린 배포는 현재 운영 환경과 동일한 새 환경을 준비한 뒤 트래픽을 한 번에 전환하는 배포 방식임
- **배경/필요성**: 잦은 배포 환경에서는 전체 사용자에게 한 번에 배포할 경우 장애 영향 범위가 커지므로, 점진 검증과 신속 복구가 가능한 배포 전략이 필요함

## Ⅱ. 특징

- 카나리는 위험을 작게 나눠 관찰하면서 배포할 수 있음
- 블루-그린은 전환과 롤백이 빠르지만 이중 환경 비용이 큼
- 관측 지표와 자동 중단 조건이 없으면 전략 효과가 줄어듦
- 데이터 스키마 변경은 배포 전략과 별도로 호환성 설계가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 카나리 배포 | 블루-그린 배포 |
|:---|:---|:---|
| 트래픽 전환 | 점진 확대 | 한 번에 전환 |
| 장점 | 위험 범위 작음 | 롤백 빠름 |
| 한계 | 관측과 제어 복잡 | 이중 환경 비용 큼 |
| 적합 환경 | 지속적 배포와 온라인 서비스 | 명확한 스위치 전환 서비스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Traffic Splitter | 카나리에서 사용자 비율을 조절해 노출 범위를 점진적으로 확대함 |
| Blue and Green Environment | 블루-그린에서 현재와 신규 환경을 병행 유지해 즉시 전환과 복구를 가능하게 함 |
| Health Metric Gate | 오류율과 지연과 비즈니스 지표를 기준으로 배포 지속 여부를 판정함 |
| Rollback Mechanism | 이상 징후 시 즉시 트래픽을 원래 버전으로 되돌리는 복구 경로임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 신규 버전 배치   | --> | 제한 또는 병행 노출 | --> | 지표 검증      | --> | 확대 또는 롤백 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **신규 버전 배치**: 새 아티팩트를 별도 환경이나 일부 대상에 배치함
2. **제한 또는 병행 노출**: 카나리는 소량 트래픽, 블루-그린은 병행 환경을 준비함
3. **지표 검증**: 오류와 지연과 전환 지표를 확인함
4. **확대 또는 롤백**: 기준 충족 시 확대하고 아니면 즉시 복구함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 배포 전략만 있고 자동 중단 기준이 없으면 오류가 커질 때까지 확대가 진행될 수 있음
   - 해결방안: SLO 기반 배포 게이트를 두고 canary abort precision과 rollback time으로 검증함
2. 문제: 블루-그린은 애플리케이션 전환은 쉬워도 데이터 스키마가 비호환이면 즉시 롤백이 어려울 수 있음
   - 해결방안: backward-compatible schema 전략을 적용하고 schema rollback readiness와 release success rate로 검증함
3. 문제: 카나리 대상 선정이 왜곡되면 실제 전체 사용자 영향과 다른 결론을 낼 수 있음
   - 해결방안: 대표성 있는 트래픽 샘플링을 적용하고 canary representativeness score와 false positive rollback rate로 검증함

## Ⅶ. 적용 사례

- 온라인 결제 서비스에서는 카나리 배포를 사용하고, canary abort precision과 p99 latency로 결과를 확인함
- 대형 웹 플랫폼에서는 블루-그린 환경을 운영하고, rollback time과 release success rate로 결과를 확인함
- 데이터 스키마 변경이 있는 릴리스에서는 호환성 전략을 병행하고, schema rollback readiness와 false positive rollback rate로 결과를 확인함

## Ⅷ. 결론

카나리와 블루-그린 배포의 차이는 방식보다 위험을 어디서 얼마나 관측하며 되돌릴 수 있느냐에 있고, 그 핵심은 지표와 롤백 준비도임.
