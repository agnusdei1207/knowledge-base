## Ⅰ. 개요
- 정의: 테스트 설계와 수행을 동시에 진행하며, 테스터의 지식과 경험에 의존하는 방식
- 배경: 정형화된 테스트 케이스(TC)만으로는 발견하기 어려운 예외적 결함 식별 필요
- 출제 의도: 스크립트 기반 테스팅과의 차이점 및 세션 기반 테스팅 기법 이해

## Ⅱ. 구성요소
- 구조도
  [Learning] <--- [Design] <--- [Execution]
       |             ^            |
       +-------------+------------+
       (Feedback Loop within a Session)

- 구성요소 표
| 구성요소 | 설명 | 역할 |
| :--- | :--- | :--- |
| 차터(Charter) | 테스트의 목적, 범위, 제약 사항 정의 | 탐험 지도 |
| 세션(Session) | 집중적인 테스팅을 수행하는 일정 시간 단위 | 탐험 활동 |
| 디브리핑 | 결과 공유 및 후속 테스트 방향 논의 | 탐험 보고 |
> 요약: 차터 범위 안에서 학습·설계·실행을 반복하고 발견 결과에 따라 다음 경로를 선택함

## Ⅲ. 절차
- 흐름도
  차터 작성 -> 세션 수행 -> 결함 기록 -> 결과 분석/브리핑
- 4단계 설명
1. 차터 작성: 무엇을 테스트할지 핵심 목표와 아이디어를 간략히 기술
2. 세션 수행: 정해진 시간(예: 90분) 동안 자유롭게 조작하며 시스템 학습 및 검증
3. 결함 기록: 발견된 문제점과 테스트 경로를 실시간으로 메모/캡처
4. 결과 분석: 수행한 내용 중 취약 구간을 식별하고 추가 테스팅 필요성 판단
> 요약: 세션별 탐색 경로·관찰 결과·결함을 기록하고 디브리핑에서 후속 테스트를 결정함

## Ⅳ. 문제점
- 테스터의 개인 역량(도메인 지식 등)에 따라 테스트 품질 편차가 크게 발생
- 수행 경로를 체계적으로 기록하지 않을 경우 결함 재현 및 테스트 보장성 확인 곤란

## Ⅴ. 개선방안
- 세션 기반 테스팅(SBT) 관리 도구를 활용하여 활동 시간 및 산출물 기록 표준화
- 숙련된 테스터와 초급 테스터의 페어 테스팅(Pair Testing)을 통한 역량 전수

## Ⅵ. 전망
- 인공지능(RL 기반) 에이전트가 탐색적 테스팅의 시나리오를 자동 생성하는 기술 발전
- CSF: 정형화된 테스트와 탐색적 테스팅의 적절한 조합(Blending) 전략 수립
