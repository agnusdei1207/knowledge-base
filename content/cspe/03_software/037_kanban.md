## 미리 알고가기

- 칸반은 작업 흐름을 시각화하고 WIP를 제한해 흐름 효율을 높이는 방식임
- pull 기반 운영이어서 수요가 생길 때 다음 작업을 끌어옴
- cycle time과 throughput과 blocked item이 핵심 지표임

## Ⅰ. 개요

- **정의/개념**: 칸반은 작업 단계를 보드에 시각화하고 각 단계의 동시 진행 작업 수를 제한해 흐름 병목을 드러내고 리드타임을 줄이는 업무 관리 방식임
- **배경/필요성**: 작업이 많아질수록 동시 착수와 컨텍스트 전환이 늘어 완료 속도가 오히려 느려지므로, 시작보다 완료 흐름을 중심으로 관리하는 체계가 필요함

## Ⅱ. 특징

- 스프린트 고정보다 지속 흐름과 작업 완료 속도를 중시함
- WIP 제한으로 병목과 과부하를 조기에 드러냄
- 우선순위 변동이 잦은 운영형 조직에 적합함
- 규칙이 느슨하면 단순한 할 일 게시판으로 전락할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 스크럼 | 칸반 |
|:---|:---|:---|
| 운영 주기 | sprint 중심 | 연속 흐름 중심 |
| 계획 방식 | 주기별 계획 | pull 기반 우선순위 반영 |
| 핵심 통제 | sprint goal | WIP limit와 flow efficiency |
| 적합 환경 | 제품 반복 개발 | 운영, 지원, 지속 개선 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Kanban Board | 작업 단계와 상태를 시각화해 병목 위치와 진행량을 즉시 보여줌 |
| WIP Limit | 각 단계의 동시 작업 수를 제한해 몰림과 컨텍스트 전환을 줄임 |
| Pull Rule | 다음 단계 여유가 있을 때만 작업을 가져오게 해 흐름 균형을 유지함 |
| Flow Metric | cycle time과 throughput과 blocked time이 개선 여부를 판단하는 핵심 지표가 됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 등록      | --> | 단계별 시각화   | --> | WIP 제한 운영   | --> | 흐름 개선      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 등록**: 업무 항목을 카드 단위로 정의함
2. **단계별 시각화**: 분석과 개발과 검토와 배포 같은 흐름 단계를 보드에 배치함
3. **WIP 제한 운영**: 각 단계 한도를 넘지 않도록 pull 방식으로 처리함
4. **흐름 개선**: 병목과 지연 원인을 측정해 규칙을 조정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: WIP 제한 없이 칸반을 쓰면 진행 중 작업이 과도하게 늘어 완료 속도가 오히려 늦어질 수 있음
   - 해결방안: 단계별 WIP limit를 명확히 두고 flow efficiency와 cycle time으로 검증함
2. 문제: 우선순위 규칙이 불명확하면 긴급 작업이 계속 끼어들어 정상 흐름이 무너질 수 있음
   - 해결방안: expedite lane과 우선순위 기준을 운영하고 blocked item age와 expedite ratio로 검증함
3. 문제: 보드만 시각화하고 병목 분석을 하지 않으면 개선 없이 현황판 역할만 하게 될 수 있음
   - 해결방안: 정기 flow review를 수행하고 throughput trend와 bottleneck recurrence rate로 검증함

## Ⅶ. 적용 사례

- 운영 지원 조직에서는 칸반 보드를 사용하고, cycle time과 blocked item age로 결과를 확인함
- 플랫폼 팀에서는 WIP 제한과 expedite lane을 운영하고, expedite ratio와 throughput trend로 결과를 확인함
- 고객 요청 처리 조직에서는 병목 단계를 정기 점검하고, flow efficiency와 bottleneck recurrence rate로 결과를 확인함

## Ⅷ. 결론

칸반의 본질은 보드 시각화가 아니라 시작 작업 수를 억제해 완료 흐름을 안정시키는 운영 규율에 있음.
