# 📖 【암기용】 개념 완전 이해

> 목적: SP 인증을 소프트웨어 개발 조직의 프로세스 역량을 평가·개선하는 제도로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: SP 인증은 SW 개발·관리 프로세스 품질 수준을 심사해 등급화하는 제도
- **왜 필요한가**: 결과물 품질은 개인 역량만으로 유지되지 않고 요구관리, 형상관리, 테스트, 프로젝트관리 프로세스에 좌우된다.
- **핵심 직관**: 음식 맛을 한 번 평가하는 것이 아니라 주방 위생, 재료 관리, 조리 절차를 평가해 재현 가능한 품질을 보는 방식임.

## 깊이 이해
- **배경·문제의식**: SW 기업은 프로젝트마다 관리 방식이 달라 일정 지연, 결함 증가, 인수인계 실패가 반복될 수 있음.
- **작동 원리**: 조직의 프로젝트관리, 개발, 지원, 프로세스 개선 활동을 심사 기준에 맞춰 평가하고 미흡 항목을 개선 로드맵으로 관리함.
- **비유**: 운전면허가 개인 운전 능력을 보는 것이라면, SP 인증은 운송회사의 차량 점검·배차·안전교육 체계를 보는 것과 같음.
- **구체 예시**: 요구사항 변경관리 미흡으로 등급 목표에 미달하면 변경요청 승인 절차, 영향분석 양식, 형상관리 링크를 개선 과제로 등록함.
- **흔한 오해·주의점**: SP 인증은 문서 보유 경쟁이 아니라 실제 프로젝트에서 프로세스가 실행되고 지표로 관리되는지를 보는 평가임.

## 연결 개념
- CMMI: 프로세스 성숙도 모델
- ISO 29119: 테스트 프로세스 표준
- DevOps Metrics: 프로세스 운영 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SP 인증 답안은 심사 영역, 등급, 증적, 개선 로드맵, 지표 기반 운영을 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SP 인증은 SW 조직의 프로젝트관리, 개발, 지원, 프로세스 개선 역량을 심사해 품질 수준을 평가하는 제도이다.
> 2. **가치**: 요구관리, 형상관리, 테스트, 결함관리 절차를 표준화해 프로젝트별 편차를 줄이고 재현 가능한 품질 체계를 만든다.
> 3. **판단 포인트**: 인증 획득보다 심사 지적사항을 개선 로드맵과 운영 지표로 연결해야 지속 개선 효과를 얻는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로세스 품질 인증 이해 확인 | SP 인증, 심사 영역, 등급, 증적 | 단순 제품 품질 인증으로 설명하지 않음 |
| 개선 로드맵 역량 확인 | Gap 분석, 개선과제, 재심사 | 문서 작성만으로 인증 대응을 끝내지 않음 |
| 실무 운영 판단 확인 | 요구·형상·테스트·결함관리 지표 | 인증 후 방치 리스크를 누락하지 않음 |
> 요약: SP 인증은 조직 프로세스 실행 증거와 개선 지표를 통해 SW 품질 역량을 평가하는 제도이다.

---

## Ⅰ. 개요 및 필요성

SP 인증은 SW 프로세스 품질 인증 제도이다.
SW 품질은 개발자 개인 역량보다 요구관리, 프로젝트관리, 테스트, 형상관리 절차의 반복 실행 여부에 크게 좌우된다.
조직 차원의 프로세스 역량을 심사하고 개선하면 프로젝트별 품질 편차와 납기 지연을 줄일 수 있다.

---

## Ⅱ. 구조 및 구성요소

```text
조직 프로세스 기준 -> 프로젝트 수행 증적 -> 심사 평가
-> 등급 판정 -> Gap 분석 -> 개선 로드맵
-> 지표 운영 -> 재심사/지속 개선
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| 심사 기준 | 프로세스 평가 항목 | 관리·개발·지원·개선 영역 |
| 수행 증적 | 실제 실행 근거 | 계획서, 회의록, 형상 로그 |
| 등급 판정 | 품질 수준 판단 | 충족·미흡 항목 |
| 개선 로드맵 | 미흡 프로세스 보완 | 우선순위와 일정 |
> 요약: SP 인증은 기준, 증적, 등급, 개선 과제를 연결해 조직 프로세스를 평가한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
현행 프로세스 진단 -> 심사 기준 매핑 -> 증적 수집
-> 내부 심사 -> 공식 심사 -> 등급 판정
-> 지적사항 개선 -> 운영 지표 모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 프로세스 자가진단 | 기준 항목 매핑률 100% |
| 2 | 프로젝트 증적 수집 | 최근 프로젝트 표본 확보 |
| 3 | 내부 심사와 Gap 분석 | 미흡 항목 목록화 |
| 4 | 공식 심사와 등급 판정 | 심사 결과서 |
| 5 | 개선 로드맵 실행 | 개선과제 완료율 90% 이상 |
> 요약: SP 인증은 심사 준비보다 지적사항을 개선과제와 운영 지표로 전환하는 과정이 핵심이다.

## Ⅳ. 특징

| 구분 | 제품 품질 평가 | SP 인증 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 평가 대상 | 결과물 기능·결함 | 조직 프로세스 실행력 | 프로젝트 표본 증적 |
| 증거 | 테스트 결과 | 계획·관리·형상·리뷰 로그 | 증적 누락 0건 |
| 효과 | 특정 제품 품질 확인 | 반복 가능한 품질 체계 | 결함 재오픈율 5% 이하 |
| 한계 | 조직 개선 범위 작음 | 문서 형식화 위험 | 지표 기반 운영 필요 |
> 요약: SP 인증은 제품 1개의 품질보다 조직이 품질을 반복 생산할 수 있는 절차와 증적을 평가한다.

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 프로젝트별 임시 절차 | 조직 표준 프로세스 | 다수 프로젝트 동시 수행 |
| 비용/규모 | 단기 문서 작업 | 교육·도구·내부심사 비용 | 인증·공공사업 요구 |
| 운영/위험 | 담당자 의존 | 프로세스 지표 관리 | 이직·외주 비중 높음 |
| 품질 | 결과물 검사 중심 | 과정 품질과 개선 | 결함·납기 편차 큰 조직 |
> 요약: SP 인증은 반복 프로젝트를 수행하는 조직에서 프로세스 편차를 줄이고 공공사업 신뢰도를 확보할 때 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 문서 형식화 | 실제 실행 없는 증적 | 도구 로그 기반 증거 수집 | 증적-도구 일치율 |
| 인증 후 방치 | 개선 책임자 부재 | 개선과제 Owner 지정 | 개선 완료율 90% 이상 |
| 현장 저항 | 절차가 개발 속도 저해 | 경량 템플릿과 자동화 | 산출물 작성 리드타임 |
| 심사 미흡 | 기준 해석 오류 | 내부 심사 2회 수행 | 심사 지적 재발률 |
> 요약: SP 인증 리스크는 문서 형식화와 인증 후 방치를 지표와 자동화로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 프로세스 준수 | 핵심 프로세스 준수율 95% | 내부 심사 체크리스트 |
| 결함관리 | 결함 재오픈율 5% 이하 | 결함관리 도구 |
| 형상관리 | 승인 없는 변경 0건 | Git·배포 로그 |
| 개선활동 | 개선과제 완료율 90% 이상 | 개선 로드맵 대시보드 |
> 요약: SP 인증 성과는 준수율, 결함 재오픈율, 형상 변경 통제, 개선과제 완료율로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 요구관리, 형상관리, 테스트, 결함관리 프로세스를 표준 템플릿과 도구 워크플로로 연결함.
2. 내부 심사를 최소 2회 수행하고 미흡 항목을 우선순위, Owner, 완료일이 있는 개선 로드맵으로 관리함.
3. 인증 후 분기별 프로세스 지표를 경영 리뷰에 보고하고 결함 재오픈율 5% 이하를 개선 목표로 설정함.

**결론 (2줄):**
- 기술사 판단: 공공사업·다수 프로젝트 수행 조직은 SP 인증을 품질 체계 기준으로 활용하고, 소규모 제품팀은 핵심 프로세스 위주로 Tailoring함.
- 향후 방향: SP 인증 대응은 ALM·DevOps 도구 로그와 연결되어 증적 자동 수집과 지속 프로세스 개선으로 발전함.
