# 📖 【암기용】 개념 완전 이해

> 목적: SP 인증을 소프트웨어 개발 조직의 프로세스 역량을 평가·개선하는 제도로 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 설명이다.

## 한눈에
- **개요**: SP인증(SW Process Quality Certification)은 조직의 **SW 개발·관리 프로세스 성숙도**를 심사해 등급을 부여하는 국내 SW 프로세스 품질인증 제도다.
- **왜 필요한가**: 결과물 품질은 개발자 한 명의 실력이 아니라 요구관리·형상관리·테스트·프로젝트관리 절차가 프로젝트마다 반복 실행되는지에 좌우된다. 절차가 특정 사람의 머릿속에만 있으면 그 사람이 빠지는 순간 품질이 무너진다.
- **핵심 직관**: 한 그릇의 음식 맛을 평가하는 게 아니라, 주방의 위생·재료 관리·조리 절차를 평가해서 "다음에도 같은 맛이 나올 것"을 보증하는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| SP인증 | 조직의 SW 프로세스 성숙도를 심사·등급화하는 제도 — 이 문서의 대상 | 상위 키워드 |
| 프로세스 성숙도 | 프로세스가 문서화·실행·측정·개선되는 수준 | 상위 키워드 |
| 심사기준(Assessment Model) | 프로젝트관리·개발·지원·프로세스개선 영역별 평가 항목 | 채점 기준표 |
| 수행 증적(Evidence) | 프로세스가 실제로 실행됐음을 보여주는 계획서·회의록·형상관리 로그 | 출석부·업무일지 |
| 문서심사/현장심사 | 제출 문서를 먼저 보고, 이후 현장에서 실제 운영 여부를 확인하는 2단계 심사 | 서류전형+면접 |
| 등급 판정 | 심사 영역별 충족/미흡 결과를 종합해 매기는 인증 등급 | 성적 등급 |
| Gap 분석 | 심사기준 대비 무엇이 미흡한지 찾아내는 활동 | 건강검진 결과지 |
| 개선 로드맵 | Gap을 메우기 위한 과제·우선순위·담당자·일정 계획 | 처방전과 치료 일정 |
| CMMI | 해외에서 널리 쓰는 프로세스 성숙도 모델(1~5단계) — SP인증과 목적은 같고 평가 체계가 다른 비교 대상 | 유사한 해외 자격증 |

## 깊이 이해

### 왜 이 제도가 필요했나 (배경)
- 소프트웨어는 눈에 보이는 재고나 완제품이 없어서, 발주자가 "이 조직이 안정적으로 개발할 능력이 있는가"를 결과물 하나만 보고 판단하기 어렵다. 특히 공공사업·다수 협력사가 얽힌 프로젝트는 감리·감사 시점에 "왜 이 결함이 났는가"를 프로세스로 설명해야 한다.
- 조직이 프로젝트마다 다른 방식으로 요구사항을 관리하면 변경 승인 없이 코드가 바뀌는 일이 반복되고, 이는 재작업과 납기 지연으로 이어진다. SP인증은 이런 프로세스 편차를 표준 심사기준으로 드러낸다.

### 심사가 실제로 어떻게 진행되나
- 조직은 먼저 심사기준(프로젝트관리·개발·지원·프로세스개선 등 영역)에 맞춰 자체 프로세스를 정비하고, 최근 완료했거나 진행 중인 프로젝트 중 표본을 골라 증적(계획서, 형상관리 로그, 리뷰 기록 등)을 준비한다.
- 심사는 제출 문서를 검토하는 문서심사와, 실제 현장에서 그 문서대로 프로세스가 돌아가는지 인터뷰·로그 확인으로 검증하는 현장심사 2단계로 이뤄진다. 문서만 있고 실행 증적이 없으면 미흡으로 판정된다.
- 예: "요구사항 변경관리" 항목을 심사할 때, 변경요청서 양식만 있고 실제 최근 프로젝트에서 변경요청서 없이 코드가 바뀐 이력이 형상관리 로그에서 발견되면 이 항목은 미흡(Gap)으로 기록된다.

### 등급과 Gap 분석, 개선 로드맵으로 이어지는 흐름
- 심사 영역(예: 프로젝트관리·개발·지원·개선 4개 영역)마다 충족/미흡 항목의 비율로 등급이 갈린다. 미흡 항목은 그 자리에서 끝나지 않고 Gap 분석 보고서로 정리된다.
- 예: "형상관리" 영역에서 점검 항목 20개 중 4개가 미흡(미흡률 20%)으로 나오면, 이 4개를 우선순위·담당자·완료일이 명시된 개선 로드맵에 올리고 다음 심사(재심사) 때 해소 여부를 확인한다.

### CMMI와의 관계 — 왜 비교되는가
- CMMI(Capability Maturity Model Integration)는 해외에서 널리 쓰이는 프로세스 성숙도 모델로, 초기(Level 1)부터 최적화(Level 5)까지 5단계로 조직 역량을 평가한다. SP인증은 국내 SW산업 실정(중소기업 비중이 높은 구조)에 맞춰 만들어진, 유사한 목적의 인증 체계다.
- 둘 다 "결과물이 아니라 그 결과물을 만드는 과정(프로세스)을 평가한다"는 철학은 같다. 차이는 심사 체계와 인증 등급 구성 방식이다. CMMI는 SEI가 만들고 현재 CMMI Institute(ISACA 산하)가 관리하는 반면, SP인증은 국내 SW산업 진흥 목적으로 별도 운영된다.

### 비유와 흔한 오해
- **비유**: 운전면허가 "이 사람이 운전을 잘하는가"를 보는 개인 자격증이라면, SP인증은 "이 운송회사가 차량 점검·배차·안전교육을 체계적으로 운영하는가"를 보는 조직 인증이다. 기사 한 명이 운전을 잘해도 회사의 정비 절차가 없으면 사고는 반복된다.
- **오해**: SP인증은 문서를 많이 만드는 경쟁이 아니다. 문서는 있는데 실제 프로젝트에서 그 절차대로 안 돌아가면(예: 리뷰 기록은 있지만 실제 리뷰는 형식적으로 몇 분 만에 끝남) 심사에서 그대로 드러난다. 심사자는 문서와 증적(로그·인터뷰)을 대조해서 "진짜 실행되는지"를 본다.

## 연결 개념
- CMMI — 해외에서 널리 쓰이는 유사 목적의 프로세스 성숙도 모델
- ISO 29119 — SP인증이 심사하는 프로세스 영역 중 테스트 프로세스에 해당하는 세부 표준
- DevOps Metrics — 인증 이후 프로세스가 실제로 유지되는지 보여주는 운영 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SP 인증 답안은 심사 영역, 등급, 증적, 개선 로드맵, 지표 기반 운영을 연결해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SP 인증은 SW 조직의 프로젝트관리, 개발, 지원, 프로세스 개선 역량을 심사해 품질 수준을 평가하는 제도이다.
> 2. **가치**: 요구관리, 형상관리, 테스트, 결함관리 절차를 표준화해 프로젝트별 편차를 줄이고 재현 가능한 품질 체계를 만든다.
> 3. **판단 포인트**: 인증 획득보다 심사 지적사항을 개선 로드맵과 운영 지표로 연결해야 지속 개선 효과를 얻는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로세스 품질 인증 이해 확인 | SP 인증, 심사 영역, 등급, 증적 | 단순 제품 품질 인증으로 설명하지 않음 |
| 개선 로드맵 역량 확인 | Gap 분석, 개선과제, 재심사 | 문서 작성만으로 인증 대응을 끝내지 않음 |
| 실무 운영 판단 확인 | 요구·형상·테스트·결함관리 지표 | 인증 후 방치 리스크를 누락하지 않음 |
> 요약: SP 인증은 조직 프로세스 실행 증거와 개선 지표를 통해 SW 품질 역량을 평가하는 제도이다.

## Ⅰ. 개요 및 필요성

- 개요: SW 프로세스 품질 인증
- 배경: SW 품질은 개발자 개인 역량뿐 아니라 요구관리, 프로젝트관리, 테스트, 형상관리 절차가 반복 실행되는지에 좌우된다.
- 필요성: SP 인증은 조직의 프로세스 역량을 심사해 프로젝트별 품질 편차, 납기 지연, 재작업 원인을 개선 과제로 도출한다.

---

## Ⅱ. 구조 및 구성요소

```text
조직 프로세스 기준 -> 프로젝트 수행 증적 -> 심사 평가
-> 등급 판정 -> Gap 분석 -> 개선 로드맵
-> 지표 운영 -> 재심사/지속 개선
```

| 구성요소 | 역할 | 산정 포인트 |
|:---|:---|:---|
| 심사 기준 | 프로세스 평가 항목 | 관리·개발·지원·개선 영역 |
| 수행 증적 | 실제 실행 근거 | 계획서, 회의록, 형상 로그 |
| 등급 판정 | 품질 수준 판단 | 충족·미흡 항목 |
| 개선 로드맵 | 미흡 프로세스 보완 | 우선순위와 일정 |
> 요약: SP 인증은 기준, 증적, 등급, 개선 과제를 연결해 조직 프로세스를 평가한다.

## Ⅲ. 동작원리 및 흐름도

```text
현행 프로세스 진단 -> 심사 기준 매핑 -> 증적 수집
-> 내부 심사 -> 공식 심사 -> 등급 판정
-> 지적사항 개선 -> 운영 지표 모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 프로세스 자가진단 | 기준 항목 매핑률 100% |
| 2 | 프로젝트 증적 수집 | 최근 프로젝트 표본 확보 |
| 3 | 내부 심사와 Gap 분석 | 미흡 항목 목록화 |
| 4 | 공식 심사와 등급 판정 | 심사 결과서 |
| 5 | 개선 로드맵 실행 | 개선과제 완료율 90% 이상 |
> 요약: SP 인증은 심사 준비보다 지적사항을 개선과제와 운영 지표로 전환하는 과정이 핵심이다.

> 요약: SP 인증은 제품 1개의 품질보다 조직이 품질을 반복 생산할 수 있는 절차와 증적을 평가한다.

| 비용/규모 | 단기 문서 작업 | 교육·도구·내부심사 비용 | 인증·공공사업 요구 |
| 운영/위험 | 담당자 의존 | 프로세스 지표 관리 | 이직·외주 비중 높음 |
| 품질 | 결과물 검사 중심 | 과정 품질과 개선 | 결함·납기 편차 큰 조직 |
> 요약: SP 인증은 반복 프로젝트를 수행하는 조직에서 프로세스 편차를 줄이고 공공사업 신뢰도를 확보할 때 적합하다.

| 인증 후 방치 | 개선 책임자 부재 | 개선과제 Owner 지정 | 개선 완료율 90% 이상 |
| 현장 저항 | 절차가 개발 속도 저해 | 경량 템플릿과 자동화 | 산출물 작성 리드타임 |
| 심사 미흡 | 기준 해석 오류 | 내부 심사 2회 수행 | 심사 지적 재발률 |
> 요약: SP 인증 리스크는 문서 형식화와 인증 후 방치를 지표와 자동화로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 프로세스 준수 | 핵심 프로세스 준수율 95% | 내부 심사 체크리스트 |
| 결함관리 | 결함 재오픈율 5% 이하 | 결함관리 도구 |
| 형상관리 | 승인 없는 변경 0건 | Git·배포 로그 |
| 개선활동 | 개선과제 완료율 90% 이상 | 개선 로드맵 대시보드 |
> 요약: SP 인증 성과는 준수율, 결함 재오픈율, 형상 변경 통제, 개선과제 완료율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 요구관리, 형상관리, 테스트, 결함관리 프로세스를 표준 템플릿과 도구 워크플로로 연결함.
2. 내부 심사를 최소 2회 수행하고 미흡 항목을 우선순위, Owner, 완료일이 있는 개선 로드맵으로 관리함.
3. 인증 후 분기별 프로세스 지표를 경영 리뷰에 보고하고 결함 재오픈율 5% 이하를 개선 목표로 설정함.

**결론 (2줄):**
- 기술사 판단: 공공사업·다수 프로젝트 수행 조직은 SP 인증을 품질 체계 기준으로 활용하고, 소규모 제품팀은 핵심 프로세스 위주로 Tailoring함.
- 향후 방향: SP 인증 대응은 ALM·DevOps 도구 로그와 연결되어 증적 자동 수집과 지속 프로세스 개선으로 발전함.
