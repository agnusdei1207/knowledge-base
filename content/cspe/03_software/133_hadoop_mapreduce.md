## 핵심 인사이트 (3줄 요약)
- 1대의 100억 원짜리 슈퍼컴퓨터로 처리하던 빅데이터를, 100만 원짜리 **싸구려 일반 컴퓨터(Commodity Hardware) 10,000대를 묶어서 병렬로 처리**해 버리는 2010년대 빅데이터 혁명의 시발점.
- 거대한 데이터를 64MB 블록으로 쪼개어 수만 대의 컴퓨터에 흩뿌려 저장하는 **HDFS(분산 파일 시스템)**와, 그 흩어진 데이터가 있는 곳으로 코드를 보내서 각자 계산(Map)한 뒤 하나로 모으는(Reduce) **MapReduce 알고리즘**이 핵심.
- '데이터를 서버로 가져오는 것'에서 **'서버(연산)를 데이터가 있는 곳으로 보내는 것'**으로 컴퓨팅의 철학을 180도 뒤집었으나, 디스크 I/O가 너무 느려 현재는 Spark에게 왕좌를 물려주고 스토리지(데이터레이크) 용도로만 남음.

## Ⅰ. 개요 및 필요성
- **개요**: 아파치 소프트웨어 재단에서 만든 오픈소스 프레임워크로, 방대한 양의 데이터를 분산 컴퓨팅 환경에서 저장(HDFS)하고 병렬 처리(MapReduce)하는 시스템.
- **필요성**: 구글(Google)은 전 세계의 웹페이지를 긁어와서 '어떤 단어가 몇 번 쓰였나?'를 세어야 했음. RDBMS(오라클)로는 수백 페타바이트의 텍스트를 저장할 수도 없었고 쿼리를 돌리면 몇 년이 걸렸음. "싸구려 컴퓨터 수만 대가 동시에 단어를 세고, 나중에 그걸 합치면 안 될까?"라는 발상에서 출발함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **1. HDFS (Hadoop Distributed File System)**:
  - 10TB짜리 거대 파일을 128MB 단위의 수많은 블록으로 쪼갬.
  - 이 블록들을 일반 컴퓨터(DataNode) 1,000대에 던져둠. 고장 날까 봐 똑같은 블록을 3대씩 복사(Replication Factor)해 둠. (NameNode가 어디에 쪼개져 있는지 장부를 들고 있음).
- **2. MapReduce (맵리듀스 알고리즘)**:
  - **Map 단계**: "네가 들고 있는 128MB짜리 파일에서 '사과'가 몇 번 나오는지 각각 세어봐!"라고 명령(코드)을 1,000대의 컴퓨터로 전송함. (서버 1,000대가 동시에 계산하므로 속도가 1,000배 빠름).
  - **Shuffle & Sort 단계**: 비슷한 결과끼리 묶어서 목적지로 배달함.
  - **Reduce 단계**: "자, A서버는 '사과' 총합 구하고, B서버는 '바나나' 총합 구해!"라고 최종 합산(집계)을 함.

```text
[ MapReduce의 단어 세기(Word Count) 직관적 원리 ]

 📚 [ 거대한 책 (1,000페이지) ] 
 ➡️ (HDFS가 10명의 친구(노드)에게 100페이지씩 찢어서 나눠줌)

 🗺️ [ Map 단계 (각자 자리에서 계산) ] 
 친구 1: "내 100쪽에는 '안녕' 5번, '사과' 3번!"
 친구 2: "내 100쪽에는 '안녕' 2번, '사과' 8번!"
 
 🔄 [ Shuffle 단계 (단어별로 뭉치기) ]
 "안녕 담당자한테 다 몰아줘!", "사과 담당자한테 다 몰아줘!"

 📉 [ Reduce 단계 (최종 합산) ]
 담당자 1: "'안녕'은 5+2 = 총 7번입니다!"
 담당자 2: "'사과'는 3+8 = 총 11번입니다!" ➡️ (1명이 1000장 읽는 것보다 10배 빠름!)
```

## Ⅲ. 비교 및 연결
| 구분 | 전통적 RDBMS (DW) | Hadoop (HDFS + MapReduce) |
|---|---|---|
| **하드웨어 아키텍처** | 고가의 스토리지와 서버 (Scale-Up) | **저렴한 일반 PC의 군집 (Scale-Out)** |
| **데이터 스키마** | 스키마 온 라이트 (저장할 때 규격 맞춤) | **스키마 온 리드 (아무 파일이나 저장하고 읽을 때 분석)** |
| **연산 방식** | 데이터를 디스크에서 메모리로 가져와서 계산 | **데이터가 있는 디스크로 코드를 보내서 계산 (Data Locality)** |
| **처리 특성** | 실시간 트랜잭션, 빠른 응답 | **대규모 배치(Batch) 처리, 시간이 오래 걸림** |

## Ⅳ. 실무 적용 및 기술사 판단
- **하둡 에코시스템(Ecosystem)의 완성**: 맵리듀스는 Java 코드를 수백 줄 짜야 해서 너무 어려움. 기술사들은 이를 해결하기 위해 HDFS 위에 SQL만 치면 알아서 맵리듀스 코드로 바꿔주는 **Hive(하이브)**, 대용량 로그를 수집해 주는 Flume, 비정형 데이터를 가공하는 Pig 등 거대한 툴 체인(하둡 에코시스템)을 구성하여 전사적 '데이터 레이크(Data Lake)' 아키텍처를 설계함.
- **디스크 I/O 병목의 한계**: MapReduce의 치명적 단점은 Map 작업 결과를 **'하드 디스크'에 썼다가 읽고(Shuffle), 또 디스크에 쓰고(Reduce)** 한다는 점임. 반복적인 머신러닝이나 AI 학습을 돌리면 디스크 속도 때문에 세월아 네월아 하게 됨. 결국 이 디스크 병목을 없애고 모든 연산을 RAM(메모리) 위에서 처리하는 'Apache Spark'에게 분석 엔진의 자리를 뺏기게 됨.
---
## Ⅴ. 기대효과 및 결론
- "빅데이터(Big Data)"라는 단어를 전 세계 IT 산업의 표준으로 만들었으며, 정형 데이터(표)뿐만 아니라 비정형 데이터(로그, 이미지, 텍스트)를 모조리 긁어모아 비즈니스 가치를 창출할 수 있게 만든 혁명적 시스템.
- 비록 연산 엔진(MapReduce)은 구시대의 유물이 되었으나, 방대한 데이터를 찢어서 저장하는 분산 스토리지 철학(HDFS)은 오늘날 클라우드 객체 스토리지(S3)의 근간이 되어 인류의 데이터 패러다임을 영원히 바꾸어 놓았음.

### 👶 어린이를 위한 3줄 비유 설명

2. **하둡(Hadoop)**은 동네 꼬마 1,000명을 불러서 레고를 한 주먹씩(HDFS) 나눠주는 거예요.
