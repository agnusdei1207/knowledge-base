## 미리 알고가기

- HDFS는 대용량 파일을 여러 노드에 나누어 저장하는 분산 파일시스템임
- MapReduce는 데이터를 나눠 처리한 뒤 결과를 다시 모으는 배치 처리 모델임
- YARN은 여러 작업의 자원 할당과 실행을 관리하는 클러스터 자원 관리자임

## Ⅰ. 개요

- **정의/개념**: Hadoop·MapReduce·HDFS는 대용량 데이터를 여러 서버에 분산 저장하고 배치 작업을 병렬 실행해 대규모 집계와 분석을 처리하는 대표적인 빅데이터 분산 처리 구조임
- **배경/필요성**: 단일 서버로 감당하기 어려운 로그와 이벤트와 대용량 파일이 늘어나면서 저비용 서버 여러 대로 저장과 연산을 나누는 구조가 필요해짐

## Ⅱ. 특징

- 범용 서버 여러 대로 대용량 데이터를 분산 저장하고 처리할 수 있음
- Map과 Reduce로 계산 단계를 나눠 대규모 배치 집계에 적합함
- 데이터가 있는 노드 근처에서 작업을 돌려 네트워크 이동을 줄이려 함
- 중간 결과를 디스크에 많이 쓰므로 반복 분석과 실시간 처리에는 불리할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 단일 서버 처리 | Hadoop MapReduce |
|:---|:---|:---|
| 데이터 규모 | 서버 한계에 쉽게 막힘 | 노드 추가로 확장 가능함 |
| 장애 대응 | 장비 장애 영향이 큼 | 복제와 작업 재실행으로 복원력이 높음 |
| 처리 성격 | 중소 규모 업무에 단순함 | 대규모 배치 처리에 적합함 |
| 주의점 | 확장 한계가 뚜렷함 | 디스크 중심이라 반복 연산이 느릴 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| HDFS | 큰 파일을 블록으로 나눠 여러 노드에 저장함 |
| Map Task | 입력을 병렬 분할해 중간 키-값을 생성함 |
| Shuffle / Sort | 같은 키를 모아 Reduce 전에 정렬함 |
| Reduce Task | 키별 중간 결과를 집계해 최종 결과를 만듦 |
| YARN | 자원 할당과 작업 스케줄링을 담당함 |

```text
데이터 적재(HDFS) -> Map -> Shuffle/Sort -> Reduce -> 결과 저장
```

## Ⅴ. 원리 및 절차 흐름도

```text
파일 저장 -> 블록 분할 -> Map 병렬 처리 -> 키별 재분배 -> Reduce 집계 -> 결과 출력
```

1. **파일 저장**: 입력 데이터를 HDFS에 블록 단위로 저장함
2. **Map 처리**: 각 블록을 여러 작업이 병렬로 읽고 중간 결과를 만듦
3. **Shuffle / Sort**: 같은 키를 한곳으로 모으고 정렬함
4. **Reduce 집계**: 키별 값을 최종 집계함
5. **결과 저장**: 최종 데이터를 HDFS나 외부 저장소에 기록함

## Ⅵ. 실무 적용 및 유의점

1. 대규모 로그 집계와 일 배치 정산은 Hadoop MapReduce가 잘 맞지만 작은 파일이 많으면 작업 시작 오버헤드가 커지므로 파일 병합 전략과 태스크 수를 조정하고 작업 완료 시간과 작은 파일 개수와 클러스터 활용률로 확인함
2. 반복 분석과 빠른 질의가 많은 환경은 MapReduce만으로는 느릴 수 있으므로 배치와 대화형 분석 엔진을 분리하고 반복 작업 비율과 디스크 중간 출력량과 사용자 대기 시간으로 확인함

## Ⅶ. 결론

- Hadoop MapReduce는 대규모 배치 분산 처리의 기본 구조이므로 데이터 규모와 작업 성격이 배치 중심인지 먼저 판단해야 함
