## 미리 알고가기

- 피처 플래그는 코드 배포와 기능 공개 시점을 분리하는 제어 장치임
- 런타임 평가는 요청 시점에 사용자나 환경 조건을 보고 기능 활성 여부를 결정하는 과정임
- 킬 스위치는 문제가 생겼을 때 기능을 즉시 끌 수 있는 긴급 차단 플래그임

## Ⅰ. 개요

- **정의/개념**: 피처 플래그는 코드에 포함된 기능의 활성 여부를 런타임 설정으로 제어해 배포 시점과 사용자 노출 시점을 분리하는 기능 토글 메커니즘임.
- **배경/필요성**: 기능을 코드 병합과 동시에 모두 공개하면 배포 위험이 커지므로, 점진 출시와 실험과 긴급 차단을 지원하는 제어 수단이 필요함.

## Ⅱ. 특징

- 배포와 공개를 분리해 릴리스 위험을 줄임
- 사용자 그룹별 실험과 점진 확대가 가능함
- 플래그 수가 늘면 조합 복잡도와 테스트 범위가 함께 늘어남
- 만료 관리가 없으면 오래 남은 분기가 기술부채가 됨

## Ⅲ. 종류 및 비교

| 구분 | 직접 코드 배포 공개 | 피처 플래그 사용 |
|:---|:---|:---|
| 공개 시점 | 배포와 동시에 기능이 바로 노출됨 | 설정 변경으로 노출 시점을 따로 조정할 수 있음 |
| 구조상 장점 | 구조가 단순하고 운영 규칙이 적음 | 점진 출시와 실험과 긴급 차단이 쉬움 |
| 구조상 한계 | 문제 발생 시 배포 자체를 되돌려야 할 수 있음 | 분기 수와 운영 규칙이 늘어 관리 부채가 쌓일 수 있음 |
| 적합한 환경 | 단순 릴리스와 짧은 기능 수명에 맞음 | 실험과 단계적 공개가 많은 온라인 서비스에 맞음 |

> 요약: 피처 플래그의 가치는 기능을 숨기는 데 있지 않고 공개 위험을 조절하는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 플래그 정의 | 어떤 기능을 어떤 조건에서 켜고 끌지 정의해 관리 단위를 만듦 |
| 대상 규칙 | 사용자 그룹과 환경과 비율 기준으로 기능 노출 범위를 결정함 |
| 런타임 평가 | 요청 시 플래그 상태를 평가해 실행 경로를 선택함 |
| 플래그 수명주기 | 생성과 확대와 제거 시점을 관리해 장기 부채를 억제함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 플래그 생성    | --> | 대상 규칙 설정 | --> | 런타임 평가    | --> | 확대/제거 관리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **플래그 생성**: 기능별 토글을 정의함
2. **대상 규칙 설정**: 사용자와 환경과 비율 기준을 설정함
3. **런타임 평가**: 요청 시 플래그 상태로 기능 노출을 결정함
4. **확대 및 제거 관리**: 안정화 후 전체 확대하거나 코드를 정리함

## Ⅵ. 실무 적용 및 유의점

1. 점진 출시와 A/B 테스트가 잦은 서비스에서는 피처 플래그가 유용하지만 오래 남은 분기가 빠르게 부채가 되므로 만료일과 담당자를 함께 두고 오래된 플래그 수와 분기 복잡도로 확인함
2. 장애 대응용 킬 스위치를 운영하는 조직에서는 설정 오류가 사용자 경험을 흔들 수 있으므로 안전한 기본값과 변경 검증을 함께 두고 기능 차단 시간과 설정 오류 비율로 확인함

## Ⅶ. 결론

피처 플래그는 배포 위험을 줄이는 좋은 도구이지만 공개가 끝난 뒤 분기를 빠르게 없애지 않으면 오히려 기술부채가 됨.
