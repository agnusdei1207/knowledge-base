## 미리 알고가기

- 피처 플래그는 코드 배포와 기능 공개 시점을 분리하는 제어 장치임
- 런타임 평가는 요청 시점에 사용자나 환경 조건을 보고 기능 활성 여부를 결정하는 과정임
- 킬 스위치는 배포 없이 기능을 비활성화하는 긴급 차단 플래그임

## 작성 근거(검토용)

- 피처 플래그는 공개 시점, 노출·차단 방식, 관리 부채, 적용 환경을 핵심 비교축으로 선정함
- 구성과 절차는 요청 시 플래그와 대상 규칙을 평가해 실행 경로를 선택하는 흐름을 중심으로 제시함
- 실무 판단은 만료 플래그 수, 플래그별 분기 수, 기능 차단 시간, 설정 오류율로 구체화함

## Ⅰ. 개요

- **정의/개념**: 피처 플래그는 배포된 기능의 활성 여부를 런타임 설정으로 제어해 코드 배포와 사용자 공개 시점을 분리하는 장치임
- **배경/필요성**: 기능을 배포와 동시에 전체 공개하면 장애 범위가 커지므로 점진 공개·실험·긴급 차단 수단이 필요함

## Ⅱ. 특징

- 배포와 공개를 분리해 문제 발생 시 노출 대상을 제한함
- 사용자 그룹별 실험과 점진 확대가 가능함
- 플래그 수가 늘면 조합 복잡도와 테스트 범위가 함께 늘어남
- 만료 관리가 없으면 오래 남은 분기가 기술부채가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 코드 배포 공개 | 피처 플래그 사용 |
|:---|:---|:---|
| 공개 시점 | 배포와 동시에 기능이 노출됨 | 설정 변경으로 노출 시점을 따로 조정할 수 있음 |
| 노출·차단 방식 | 새 버전 배포·롤백으로 기능 상태 변경 | 사용자·환경 조건과 설정값으로 기능 상태 변경 |
| 구조상 한계 | 문제 발생 시 배포 자체를 되돌려야 할 수 있음 | 분기 수와 운영 규칙이 늘어 관리 부채가 쌓일 수 있음 |
| 대표 환경 | 배포와 공개 시점이 같은 릴리스 | 단계적 공개·A/B 테스트·킬 스위치를 운영하는 서비스 |

> 요약: 배포와 동시에 공개하면 직접 배포, 설정으로 공개 대상과 시점을 조절하면 피처 플래그 방식임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 플래그 정의 | 어떤 기능을 어떤 조건에서 켜고 끌지 정의해 관리 단위를 만듦 |
| 대상 규칙 | 사용자 그룹과 환경과 비율 기준으로 기능 노출 범위를 결정함 |
| 런타임 평가 | 요청 시 플래그 상태를 평가해 실행 경로를 선택함 |
| 플래그 수명주기 | 생성과 확대와 제거 시점을 관리해 장기 부채를 억제함 |

> 요약: 플래그와 대상 규칙으로 요청별 실행 경로를 선택하고 공개 종료 후 플래그를 제거함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 사용자 요청    | --> | 플래그 조회    | --> | 대상 규칙 평가 | --> | 기존/신규 경로 실행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **사용자 요청**: 기능이 포함된 서비스 요청을 수신함
2. **플래그 조회**: 플래그 저장소에서 기능 활성 상태를 읽음
3. **대상 규칙 평가**: 사용자·환경·비율 조건으로 노출 여부를 결정함
4. **기존·신규 경로 실행**: 판정 결과에 따라 기존 또는 신규 기능을 실행함

> 요약: 요청마다 플래그와 대상 규칙을 평가해 기존 기능 또는 신규 기능의 실행 경로를 선택함.

## Ⅵ. 실무 사례

1. 점진 출시는 사용자 비율별로 기능을 공개하고 만료 플래그 수·플래그별 분기 수를 확인함
2. 장애 대응은 킬 스위치와 비활성 기본값을 운영하고 기능 차단 시간·설정 오류율을 확인함

## Ⅶ. 결론

피처 플래그는 배포와 기능 공개를 분리하고 요청별 실행 경로를 제어하는 런타임 장치임
