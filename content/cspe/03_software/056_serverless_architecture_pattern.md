## 미리 알고가기

- 서버리스는 서버가 없는 구조가 아니라 인프라 운영 책임을 플랫폼이 더 많이 가져가는 모델임
- FaaS와 managed backend 조합이 대표 형태임
- 이벤트 기반 처리와 사용량 기반 과금이 핵심 특성임

## Ⅰ. 개요

- **정의/개념**: 서버리스 아키텍처 패턴은 애플리케이션 기능을 함수나 관리형 서비스 단위로 분해하고, 실행 인프라와 확장과 일부 운영 책임을 클라우드 플랫폼에 위임해 빠른 배포와 탄력적 실행을 구현하는 구조임
- **배경/필요성**: 짧고 불규칙한 트래픽과 빠른 기능 출시가 중요한 서비스에서는 서버 프로비저닝과 용량 계획 부담을 줄이고 이벤트 기반 실행 모델을 활용할 필요가 커짐

## Ⅱ. 특징

- 사용량 기반 과금과 자동 확장으로 초기 운영 부담을 낮춤
- 이벤트 기반 비동기 처리와 잘 맞음
- 상태 관리와 장기 실행과 cold start가 주요 제약임
- 플랫폼 종속성과 관측 한계가 설계 시 중요한 비용 요소가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 서버 기반 | 서버리스 패턴 |
|:---|:---|:---|
| 인프라 운영 | 직접 관리 비중 큼 | 플랫폼 위임 비중 큼 |
| 확장 | 사전 용량 계획 필요 | 자동 확장 유리 |
| 장점 | 실행 제어와 예측성 높음 | 빠른 개발과 사용량 최적화 |
| 한계 | 운영 부담 큼 | cold start와 벤더 종속 가능 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Function Runtime | 이벤트를 받아 짧은 작업 단위로 실행되며 서버리스의 핵심 실행 주체가 됨 |
| Event Source | API 호출과 메시지와 스케줄 같은 입력이 함수 실행을 트리거함 |
| Managed Backend | DB와 인증과 스토리지 같은 공통 기능을 플랫폼 서비스로 받아 운영 부담을 줄임 |
| Observability Layer | 분산 함수 실행의 로그와 추적을 모아 디버깅과 비용 관리를 가능하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 발생    | --> | 함수 실행      | --> | 관리형 서비스 연동 | --> | 로그/비용 분석 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **이벤트 발생**: API나 메시지나 스케줄이 함수를 호출함
2. **함수 실행**: 런타임이 코드를 짧은 실행 단위로 수행함
3. **관리형 서비스 연동**: 저장과 인증과 통신을 외부 서비스와 조합함
4. **로그 및 비용 분석**: 실행 결과와 비용과 지연을 추적함

## Ⅵ. 문제점 및 해결 방안

1. 문제: cold start와 짧은 함수 시간 제한이 지연 민감 업무에 직접 악영향을 줄 수 있음
   - 해결방안: warm strategy와 분리 배치를 적용하고 cold start latency와 p99 response time으로 검증함
2. 문제: 함수 수가 늘어날수록 배포와 추적과 권한 관리가 흩어져 운영 복잡도가 커질 수 있음
   - 해결방안: 공통 템플릿과 IaC를 운영하고 deployment consistency와 permission drift count로 검증함
3. 문제: 플랫폼 특화 기능에 과도하게 묶이면 이식성과 비용 협상력이 떨어질 수 있음
   - 해결방안: 추상화 계층과 portability 기준을 두고 vendor lock-in score와 migration effort estimate로 검증함

## Ⅶ. 적용 사례

- 이벤트 기반 알림 서비스에서는 서버리스 함수를 사용하고, cold start latency와 cost per invocation로 결과를 확인함
- 내부 업무 자동화에서는 관리형 백엔드를 조합하고, deployment consistency와 permission drift count로 결과를 확인함
- 멀티클라우드 검토 환경에서는 이식성 기준을 관리하고, vendor lock-in score와 migration effort estimate로 결과를 확인함

## Ⅷ. 결론

서버리스 패턴의 가치는 서버를 숨기는 데 있지 않고 불규칙한 이벤트 처리와 운영 자동화 이점을 플랫폼 종속 비용보다 크게 만드는 데 있음.
