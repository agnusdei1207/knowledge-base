## 핵심 인사이트 (3줄 요약)
- 클라우드 제공자(AWS, GCP 등)가 서버의 인프라(OS, 런타임, 스케일링)를 전적으로 관리하고, 개발자는 비즈니스 로직(코드)에만 집중하는 클라우드 네이티브 아키텍처.
- **FaaS(함수) + BaaS(백엔드 서비스)**의 결합으로 이루어지며, 상태를 저장하지 않는(Stateless) 단발성 이벤트 기반 처리에 최적화됨.
- 초기 구축 속도가 압도적으로 빠르고 '사용한 만큼만 지불'하여 스타트업에 이상적이나, 벤더 종속성(Lock-in)과 콜드 스타트(Cold Start) 문제가 아키텍처 설계의 주요 허들임.

## Ⅰ. 개요 및 필요성
- **개요**: 물리적/가상적 서버의 존재를 추상화하여(Server-less), 개발자가 서버 관리에 대한 고민 없이 애플리케이션을 배포하고 운영하는 설계 패턴.
- **필요성**: 기존 EC2나 컨테이너 환경은 트래픽이 없어도 24시간 켜두어야 하므로 유휴 비용(Idle Cost)이 발생했고, OS 보안 패치 등 운영(Ops) 부담이 컸음. 순수하게 "가치를 창출하는 코드"에만 비용과 시간을 쓰고 싶다는 니즈에서 출발함.
---
## Ⅱ. 아키텍처 및 핵심 원리
- **아키텍처 구성 요소**:
  1. **Event Source**: API Gateway(HTTP), S3(파일 업로드), DynamoDB(데이터 변경), Kafka/SQS(메시지 큐) 등 트리거를 발생시키는 주체.
  2. **FaaS (Function as a Service)**: 이벤트가 발생할 때만 깨어나 찰나의 순간 동안 코드를 실행하고 죽는 컴퓨팅 자원 (AWS Lambda).
  3. **BaaS (Backend as a Service)**: 인증(Cognito), DB(DynamoDB), 파일저장(S3) 등 코딩 없이 API로만 가져다 쓰는 완전 관리형 서비스.

```text
[ 전형적인 Serverless 웹 애플리케이션 아키텍처 ]

 (클라이언트)                                (AWS 클라우드 - 서버리스 영역)
 [ Web Browser ] ➡️ (정적 파일 요청) ➡️ [ S3 (React/Vue 호스팅) + CloudFront ]
        |
        ⬇️ (동적 API 호출) 
 [ API Gateway ] ➡️ (이벤트 트리거) ➡️ [ AWS Lambda (FaaS 로직) ] ➡️ [ DynamoDB (BaaS) ]
                                   (필요할 때만 수천 개 자동 스케일링)    (NoSQL 데이터 저장)
```

## Ⅲ. 비교 및 연결
| 구분 | Server-based (IaaS / EC2) | Container (CaaS / K8s) | Serverless (FaaS / BaaS) |
|---|---|---|---|
| **관리 대상** | OS, 네트워크, 런타임, 앱 | 컨테이너 이미지, 클러스터 | 오직 소스 코드 (로직) |
| **과금 기준** | 인스턴스 켜둔 시간 (시간당) | 노드 유지 시간 | 함수 실행 횟수 + 실행 시간(ms) |
| **스케일링 속도**| 수 분 (Auto Scaling Group) | 수 초 (Pod 생성) | **수 밀리초 (즉각적 무한 확장)** |
| **최적 워크로드**| 장기 실행되는 무거운 프로세스 | 복잡한 MSA, 레거시 마이그레이션 | 이벤트 구동형 간헐적 작업, 스크립트 |

## Ⅳ. 실무 적용 및 기술사 판단
- **콜드 스타트(Cold Start) 전략**: 오랫동안 호출되지 않은 Lambda 함수가 처음 깨어날 때 컨테이너를 로드하느라 1~3초의 딜레이가 발생함. 실무에서는 Java나 C#보다 콜드 스타트가 빠른 Node.js/Python을 주로 채택하며, 실시간 응답이 중요한 API는 'Provisioned Concurrency(미리 덥혀두기)'를 통해 문제를 해결해야 함.
- **분산 트레이싱의 필수화**: 서버리스는 수십 개의 함수가 연쇄적으로 서로를 호출하는 형태가 되기 쉬움(서버리스 핀볼). 에러가 나면 어디서 터졌는지 추적이 불가능하므로, AWS X-Ray나 Datadog 같은 분산 추적(Distributed Tracing) 시스템의 도입이 설계 초기 단계부터 100% 필수적임.
---
## Ⅴ. 기대효과 및 결론
- "코드 작성(Dev) 외의 모든 운영(Ops)을 클라우드에 위임한다(NoOps)"는 클라우드 컴퓨팅의 최종 진화 형태 중 하나.
- 인프라 엔지니어가 없는 조직도 대규모 트래픽을 거뜬히 소화하는 글로벌 서비스를 수일 내에 런칭할 수 있는 파괴적 혁신을 제공함.

### 👶 어린이를 위한 3줄 비유 설명
1. 예전에는 붕어빵 장사를 하려면 가게(서버)를 24시간 빌려서 손님이 없어도 계속 월세를 내야 했어요.
2. 서버리스는 손님이 "붕어빵 줘!" 하고 버튼을 누를 때만, 하늘에서 붕어빵 굽는 기계(함수)가 1초 만에 떨어져서 빵을 굽고 바로 사라지는 마법이에요.
3. 빵을 구운 딱 3초 동안의 기계 사용료만 내면 되니까, 돈도 엄청 아끼고 손님이 천 명 와도 기계가 천 개 떨어져서 아무도 안 기다려요!
