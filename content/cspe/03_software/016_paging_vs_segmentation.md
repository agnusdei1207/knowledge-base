## Ⅰ. 개요
- 정의: 메모리를 고정 크기로 나누는 페이징과 의미 단위로 나누는 세그멘테이션 기법
- 배경: 비연속 할당을 통해 단편화 문제를 해결하고 가상 메모리 효율성을 극대화하기 위함
- 출제 의도: 각 기법의 메모리 분할 기준, 주소 변환 방식 및 단편화(Fragmentation) 차이 이해

## Ⅱ. 구성요소
```
[ Paging: Fixed ]       [ Segmentation: Variable ]
+-------+-------+       +----------+----------+
| Page 0| Page 1|       |  Code    |  Stack   |
+-------+-------+       | (Seg 0)  | (Seg 1)  |
| Page 2| Page 3|       +----------+----------+
+-------+-------+       |   Data (Seg 2)      |
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 페이징 | 물리 메모리를 고정 크기(Frame)로 분할 관리 | 똑같은 크기 벽돌 |
| 세그멘테이션 | 논리적 의미(함수, 데이터 등) 단위로 가변 크기 분할 | 방 크기가 다른 가옥 |
| 단편화 | 페이징은 내부(Internal), 세그멘테이션은 외부(External) 발생 | 자투리 공간 |
> 요약: 페이징은 물리적 편의성, 세그멘테이션은 논리적 편의성에 집중함.

## Ⅲ. 절차
```
[Logical Addr] -> [Table Look-up] -> [Base + Offset] -> [Physical Addr]
```
1. CPU가 논리 주소를 생성하면 기법에 따라 번호(p/s)와 변위(d)로 분리함
2. 페이지 테이블 또는 세그먼트 맵 테이블을 통해 시작 주소(Base) 검색
3. 세그멘테이션의 경우, 변위(d)가 세그먼트 길이를 초과하는지 유효성 검사 수행
4. 검색된 물리 주소에 변위를 더하여 실제 데이터가 위치한 메모리에 접근
> 요약: 주소 변환 테이블을 매개로 논리-물리 주소를 맵핑함.

## Ⅳ. 문제점
- 원인: 페이징은 고정 크기 할당으로 인해 마지막 페이지에 내부 단편화 발생함
- 원인: 세그멘테이션은 가변 크기 해제/할당 반복으로 중간중간 외부 단편화 발생함

## Ⅴ. 개선방안
- (단기) 세그멘테이션된 페이징(Paged Segmentation) 등 혼용 기법 적용으로 단점 보완
- (중기) 가용 공간 리스트 관리 최적화 및 압축(Compaction) 기법으로 외부 단편화 제거
- (장기) 64비트 환경의 광활한 주소 공간을 고려한 다단계 또는 역 페이징 도입

## Ⅵ. 전망
- 대용량 데이터 처리를 위해 거대 페이지(Huge Page) 기술 활용도가 높아질 것임
- 하드웨어 가속기(GPU, NPU)의 메모리 관리 체계와 CPU 가상 메모리의 통합 관리가 핵심 과제임
