## 미리 알고가기

- 샤딩은 데이터를 여러 DB 노드로 수평 분산하는 확장 기법임
- 샤드 키 선택이 분산 균형과 조회 경로를 결정함
- 조인과 트랜잭션과 재샤딩이 복잡해지는 대가가 있음

## Ⅰ. 개요

- **정의/개념**: 샤딩은 하나의 논리 데이터셋을 샤드 키 기준으로 여러 독립 데이터베이스 노드에 나누어 저장해 저장 용량과 처리량을 수평 확장하는 분산 데이터 관리 방식임
- **배경/필요성**: 단일 DB 서버가 용량과 처리량 한계에 도달하면 수직 확장만으로는 비용과 한계가 커지므로, 데이터를 분산해 부하를 여러 노드에 나눌 필요가 있음

## Ⅱ. 특징

- 저장 용량과 처리량을 노드 추가로 확장할 수 있음
- 샤드 간 독립 장애 격리가 가능함
- cross-shard 조인과 트랜잭션은 구현 복잡도가 높아짐
- 샤드 키가 잘못되면 일부 노드만 과부하되는 hotspot이 발생함

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 샤딩 | 해시 샤딩 | 디렉터리 샤딩 |
|:---|:---|:---|:---|
| 분산 방식 | 키 범위별 분배 | 해시 값 균등 분산 | 매핑 테이블 기반 |
| 강점 | 범위 조회 유리 | 균형 분산 용이 | 유연한 재배치 가능 |
| 한계 | hotspot 위험 | 범위 조회 비효율 | 매핑 관리 부담 |
| 적합 업무 | 구간 조회 중심 | 균등 key access | 복합 라우팅 요구 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Shard Key | 데이터 분산과 라우팅 효율과 hotspot 가능성을 결정함 |
| Routing Layer | 요청을 올바른 샤드로 보내어 애플리케이션 복잡도를 낮춤 |
| Rebalancing Policy | 노드 추가와 데이터 편중 시 재배치를 수행함 |
| Cross-Shard Control | 샤드 간 조회와 집계와 트랜잭션을 보완하는 별도 전략을 제공함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키 분포 분석    | --> | 샤드 키 선정    | --> | 라우팅/저장     | --> | 편중/재샤딩 관리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 분포 분석**: 접근 패턴과 데이터 성장 방향을 확인함
2. **샤드 키 선정**: 균형과 조회 경로를 함께 고려함
3. **라우팅과 저장**: 요청을 해당 샤드에 배치함
4. **편중과 재샤딩 관리**: hotspot과 노드 증설을 대응함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 샤드 키가 업무 접근 패턴을 반영하지 못하면 특정 샤드에 트래픽과 데이터가 몰려 확장 효과가 사라질 수 있음
   - 해결방안: access skew 분석으로 샤드 키를 검증하고 shard balance ratio와 hot shard request rate로 검증함
2. 문제: cross-shard 질의가 많아지면 분산 비용이 커져 단일 DB보다 더 느린 구조가 될 수 있음
   - 해결방안: aggregate read model을 분리하고 cross-shard query ratio와 fan-out latency로 검증함
3. 문제: 재샤딩 절차가 준비되지 않으면 성장 시점마다 장시간 서비스 중단 위험이 생길 수 있음
   - 해결방안: online resharding playbook을 마련하고 resharding downtime과 migration success rate로 검증함

## Ⅶ. 적용 사례

- 사용자 계정 대용량 서비스에서는 샤드 키 분포를 검증하고, shard balance ratio와 hot shard request rate로 결과를 확인함
- 분석성 조회가 많은 플랫폼에서는 읽기 모델을 분리하고, cross-shard query ratio와 fan-out latency로 결과를 확인함
- 빠르게 성장하는 SaaS에서는 온라인 재샤딩 절차를 준비하고, resharding downtime과 migration success rate로 결과를 확인함

## Ⅷ. 결론

샤딩의 성공 조건은 노드를 많이 늘리는 데 있지 않고 샤드 키와 재샤딩 전략을 처음부터 운영 관점으로 설계하는 데 있음.
