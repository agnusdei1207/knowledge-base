## 미리 알고가기

- 샤딩은 하나의 논리 데이터셋을 여러 데이터베이스 노드로 나누어 저장하는 수평 분산 방식임
- 샤드 키는 어떤 데이터가 어느 노드로 갈지 정하는 기준 값임
- 재샤딩은 이미 분산된 데이터를 다른 샤드 배치로 다시 옮기는 작업이라 비용이 큼

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- 샤딩은 샤드 키·요청 라우팅·재균형을 핵심 축으로 설명함
- 비교표는 범위·해시·디렉터리 샤딩의 분산 방식과 적합 환경을 대비함
- 분산 DB는 샤드별 요청 비율·데이터 크기 편차로 검증함

## Ⅰ. 개요

- **정의/개념**: 샤딩은 하나의 논리 데이터셋을 샤드 키에 따라 여러 데이터베이스 노드에 분산해 저장 용량과 처리량을 수평 확장하는 방식임
- **배경/필요성**: 단일 DB의 저장 용량과 처리량 한계를 분산하기 위해 데이터 분포와 접근 패턴에 맞는 샤드 키와 라우팅 계층이 필요함

## Ⅱ. 특징

- 노드를 추가해 저장 용량과 처리량을 함께 확장할 수 있음
- 샤드별로 장애가 격리돼 일부 문제를 전체 장애로 번지지 않게 할 수 있음
- 샤드 간 조인·집계·트랜잭션은 여러 노드에 요청을 분산하고 결과·커밋을 조정해야 함
- 샤드 키가 잘못되면 특정 노드만 과부하되는 편중 문제가 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 샤딩 | 해시 샤딩 | 디렉터리 샤딩 |
|:---|:---|:---|:---|
| 분산 방식 | 키 값 구간별로 노드를 나눔 | 해시 결과로 노드를 고름 | 별도 매핑 정보로 노드를 찾음 |
| 라우팅 결과 | 연속 키 구간을 같은 샤드로 전달 | 해시 결과에 대응하는 샤드로 전달 | 매핑 테이블의 키·규칙에 따라 샤드 선택 |
| 한계 | 특정 구간에 요청이 몰리면 편중이 큼 | 범위 조회가 여러 샤드로 퍼지기 쉬움 | 매핑 관리 계층이 추가로 필요함 |
| 적합 환경 | 날짜나 지역 구간 조회가 많은 서비스 | 사용자 ID처럼 해시 분포가 고른 서비스 | 복잡한 라우팅 규칙이 필요한 서비스 |

> 요약: 범위 샤딩은 키 구간, 해시 샤딩은 해시 결과, 디렉터리 샤딩은 별도 매핑 정보로 노드를 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 샤드 키 | 데이터 분산과 조회 경로와 편중 가능성을 결정하는 핵심 기준임 |
| 라우팅 계층 | 요청을 어느 샤드로 보낼지 판단해 애플리케이션 복잡도를 줄임 |
| 샤드 배치 정보 | 어떤 샤드가 어느 노드에 있는지 기록해 이동과 확장을 가능하게 함 |
| 재균형 절차 | 노드 증설과 편중 발생 시 데이터를 다시 배치해 확장 효과를 유지함 |

> 요약: 샤드 키와 배치 정보가 데이터 위치를 결정하고 라우팅 계층과 재균형 절차가 분산·확장을 수행함.

## Ⅴ. 원리 및 절차 흐름도

1. **샤드 키 추출**: 요청에서 데이터 위치를 결정할 키를 읽음
2. **샤드 매핑**: 범위·해시·디렉터리 규칙으로 대상 샤드를 계산함
3. **요청 라우팅**: 대상 노드로 읽기·쓰기 요청을 전달함
4. **결과 처리**: 단일 샤드 결과를 반환하거나 여러 샤드 결과를 병합함

> 요약: 요청의 샤드 키를 노드에 매핑해 읽기·쓰기를 전달하고 필요하면 여러 샤드 결과를 병합함.

## Ⅵ. 실무 사례

1. 사용자 DB는 사용자 ID 해시 샤딩을 적용하고 샤드별 요청 비율·데이터 크기 편차를 확인함
2. 주문 검색은 별도 읽기 모델을 구성하고 다중 샤드 질의 비율·팬아웃 지연을 확인함

## Ⅶ. 결론

- 샤딩은 데이터 분포와 접근 패턴에 맞는 샤드 키·라우팅·재샤딩 전략을 함께 설계해야 함
