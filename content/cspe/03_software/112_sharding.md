## 미리 알고가기

- 샤딩은 하나의 논리 데이터셋을 여러 데이터베이스 노드로 나누어 저장하는 수평 분산 방식임
- 샤드 키는 어떤 데이터가 어느 노드로 갈지 정하는 기준 값임
- 재샤딩은 이미 분산된 데이터를 다른 샤드 배치로 다시 옮기는 작업이라 비용이 큼

## Ⅰ. 개요

- **정의/개념**: 샤딩은 하나의 논리 데이터셋을 샤드 키 기준으로 여러 독립 데이터베이스 노드에 나누어 저장해 저장 용량과 처리량을 수평으로 확장하는 분산 데이터 관리 방식임.
- **배경/필요성**: 단일 데이터베이스 서버가 용량과 처리량 한계에 도달하면 장비 증설만으로는 비용과 한계가 커지므로, 데이터를 여러 노드로 나눠 부하를 분산할 필요가 있음.

## Ⅱ. 특징

- 노드를 추가해 저장 용량과 처리량을 함께 확장할 수 있음
- 샤드별로 장애가 격리돼 일부 문제를 전체 장애로 번지지 않게 할 수 있음
- 샤드 간 조인과 집계와 트랜잭션은 구현 복잡도가 크게 올라감
- 샤드 키가 잘못되면 특정 노드만 과부하되는 편중 문제가 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 범위 샤딩 | 해시 샤딩 | 디렉터리 샤딩 |
|:---|:---|:---|:---|
| 분산 방식 | 키 값 구간별로 노드를 나눔 | 해시 결과로 노드를 고름 | 별도 매핑 정보로 노드를 찾음 |
| 강점 | 범위 조회와 보관 정책에 유리함 | 비교적 고른 분산이 쉬움 | 유연한 재배치와 복합 규칙 적용이 가능함 |
| 한계 | 특정 구간에 요청이 몰리면 편중이 큼 | 범위 조회가 여러 샤드로 퍼지기 쉬움 | 매핑 관리 계층이 추가로 필요함 |
| 잘 맞는 업무 | 날짜나 지역 구간 조회가 많은 서비스 | 사용자 ID처럼 고른 분산이 중요한 서비스 | 복잡한 라우팅 규칙이 필요한 서비스 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 샤드 키 | 데이터 분산과 조회 경로와 편중 가능성을 결정하는 핵심 기준임 |
| 라우팅 계층 | 요청을 어느 샤드로 보낼지 판단해 애플리케이션 복잡도를 줄임 |
| 샤드 배치 정보 | 어떤 샤드가 어느 노드에 있는지 기록해 이동과 확장을 가능하게 함 |
| 재균형 절차 | 노드 증설과 편중 발생 시 데이터를 다시 배치해 확장 효과를 유지함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키 분포 분석    | --> | 샤드 키 선정    | --> | 라우팅/저장     | --> | 편중/재샤딩 관리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 분포 분석**: 접근 패턴과 데이터 성장 방향을 확인함
2. **샤드 키 선정**: 균형과 조회 경로를 함께 고려해 키를 고름
3. **라우팅과 저장**: 요청을 해당 샤드로 보내어 저장함
4. **편중과 재샤딩 관리**: 특정 샤드 쏠림과 노드 증설을 대응함

## Ⅵ. 실무 적용 및 유의점

1. 사용자와 주문 데이터가 빠르게 커지는 서비스에서는 샤딩이 필요할 수 있지만 샤드 키가 접근 패턴과 맞지 않으면 특정 노드만 과열되므로 샤드별 요청 비율과 데이터 크기 편차로 확인함.
2. 여러 샤드를 동시에 읽는 집계와 검색이 많은 서비스에서는 샤딩 자체보다 읽기 모델 분리가 더 중요할 수 있으므로 샤드 간 질의 비율과 팬아웃 지연 시간을 함께 확인함.

## Ⅶ. 결론

샤딩의 성공 조건은 노드를 많이 늘리는 데 있지 않고 샤드 키와 재샤딩 전략을 처음부터 운영 관점으로 설계하는 데 있음.
