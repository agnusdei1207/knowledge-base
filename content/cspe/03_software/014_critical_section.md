## 미리 알고가기

- 임계 구역: 여러 실행 주체가 공유 데이터를 읽거나 쓰는 코드 영역임
- 상호 배제: 한 시점에 하나의 실행 주체만 임계 구역에 들어가는 조건임
- 한정 대기: 진입 요청 뒤 다른 주체가 앞서 들어갈 수 있는 횟수에 상한이 있는 조건임
- compare-and-swap(CAS): 메모리 값이 예상값과 같을 때만 새 값으로 원자적으로 바꾸는 명령임
- test-and-set(TAS): 메모리 값을 검사하고 원자적으로 1로 설정해 잠금 여부를 판정하는 명령임

## 작성 근거(검토용)

- 임계 구역 해법은 상호 배제·진행·한정 대기 세 조건으로 판정함
- 소프트웨어 알고리즘·원자적 명령·뮤텍스·모니터를 구현 위치·대기 방식·주요 제약으로 비교함
- 진입 판정·공유 상태 갱신·해제 순서를 실제 상태 전이로 유지함

## Ⅰ. 개요
- **정의/개념**: 임계 구역은 공유 데이터를 갱신하는 코드 영역이고, 상호 배제는 동시에 하나의 실행 주체만 진입하게 하는 동기화 조건임
- **배경/필요성**: 공유 데이터의 읽기·쓰기 순서에 따라 결과가 달라지는 경쟁 조건을 방지하기 위해 진입·대기·해제 규칙이 필요함

## Ⅱ. 특징

- 상호 배제는 둘 이상의 실행 주체가 임계 구역에 동시에 들어가지 못하게 함
- 진행은 임계 구역이 비어 있을 때 진입 후보 중 하나를 결정하게 함
- 한정 대기는 특정 요청이 계속 뒤로 밀리지 않도록 대기 상한을 둠
- 메모리 재정렬이 있는 하드웨어에서는 원자적 명령과 메모리 배리어가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 알고리즘 | 원자적 하드웨어 명령 | 뮤텍스·모니터 |
|:---|:---|:---|:---|
| 구현 위치 | 공유 변수·진입 프로토콜(플래그·턴 값) | CPU 원자적 명령(CAS·TAS) | 운영체제·언어 런타임(락 상태·조건 큐) |
| 대기 방식 | 바쁜 대기 | 바쁜 대기 기반 | 수면 대기 가능 |
| 주요 제약 | 재정렬·프로세스 수 제한 | 캐시 경합·CPU 소모 | 문맥 전환·해제 누락 |

> 요약: 소프트웨어 알고리즘은 공유 변수, 하드웨어 명령은 원자적 갱신, 뮤텍스·모니터는 락과 대기 큐로 진입을 통제함.

## Ⅳ. 구성요소 및 구조
```
[ 진입 구역 ] -> lock()
[ 임계 구역 ] -> 공유 데이터 갱신
[ 퇴장 구역 ] -> unlock()
[ 나머지 구역 ] -> 이후 작업 수행
```
| 구성요소 | 설명 | 판정 기준 |
| :--- | :--- | :--- |
| 상호 배제 | 한 프로세스가 실행 중이면 다른 프로세스 진입 금지 | 동시 진입 불가 |
| 진행 | 진입 가능 프로세스가 있으면 다음 진입자를 결정 | 불필요한 지연 없음 |
| 한정 대기 | 요청 후 유한 횟수 안에 진입 기회 제공 | 대기 상한 |
> 요약: 상호 배제·진행·한정 대기 충족 여부로 해법을 판단함.

## Ⅴ. 원리 및 절차 흐름도
```
[진입 요청] -> [조건 확인] -> [임계구역 실행] -> [해제 통지]
```
1. **진입 요청**: 실행 주체가 락·플래그·턴 값을 이용해 임계 구역 권한을 요청함
2. **진입 판정**: 다른 소유자가 없고 진입 조건을 만족하면 권한을 획득함
3. **공유 상태 갱신**: 임계 구역에서 공유 데이터를 읽고 변경함
4. **해제·통지**: 락이나 진입 상태를 해제해 대기 주체의 재시도를 허용함
> 요약: 진입 전 권한 확인과 종료 후 해제로 공유 데이터 동시 갱신을 방지함.

## Ⅵ. 실무 사례

1. 공유 세션 캐시는 뮤텍스로 갱신 구역을 보호하고 경쟁 조건 발생 수와 락 대기시간을 확인함
2. 커널 락 구현은 원자적 명령과 메모리 배리어를 적용하고 동시 진입 수와 스핀시간을 확인함

## Ⅶ. 결론

- 임계 구역 해법은 상호 배제·진행·한정 대기를 만족하면서 대기 방식과 메모리 모델에 맞게 선택함
