## Ⅰ. 개요
- 정의: 공유 자원에 접근하는 프로그램 코드 영역과, 이를 한 번에 하나만 실행하게 하는 원칙
- 배경: 다중 프로세스가 동일 데이터를 조작할 때 발생하는 경쟁 조건 및 부정확한 결과 방지
- 출제 의도: 임계 구역 문제 해결을 위한 3가지 필수 조건 및 구현 알고리즘의 이해

## Ⅱ. 구성요소
```
[ Entry Section ]   -> lock()
[ Critical Section ] -> shared_data++
[ Exit Section ]    -> unlock()
[ Remainder Section] -> other_tasks()
```
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 상호 배제 | 한 프로세스가 실행 중이면 다른 프로세스 진입 금지 | 1인실 사용 |
| 진행 | 진입하려는 프로세스들 중 적절히 선택하여 지연 방지 | 공정한 순번 |
| 한정 대기 | 무한정 기다리지 않도록 진입 횟수 제한 | 대기 시간 보장 |
> 요약: Mutual Exclusion, Progress, Bounded Waiting의 3요소 충족이 핵심임.

## Ⅲ. 절차
```
[Entry Req] -> [Condition Check] -> [CS Execution] -> [Release Notify]
```
1. 프로세스가 임계 구역 진입 전 진입 구역(Entry Section)에서 권한 요청
2. 현재 실행 중인 다른 프로세스가 없는지 플래그나 턴 정보를 확인
3. 권한 획득 후 임계 구역 내의 명령어를 수행하여 공유 자원 업데이트
4. 종료 후 퇴출 구역(Exit Section)에서 상태를 해제하여 대기 중인 타 프로세스 허용
> 요약: 코드의 원자성(Atomicity)을 보장하기 위한 사전/사후 절차를 수행함.

## Ⅳ. 문제점
- 원인: 잘못된 구현으로 상호 배제는 지켜지나 진행이 안 되는 라이브락(Livelock) 발생
- 원인: 하드웨어의 명령어 재정렬(Instruction Reordering)로 인한 의도치 않은 결과 초래

## Ⅴ. 개선방안
- (단기) 피터슨(Peterson) 알고리즘 등 소프트웨어적 해결책 또는 하드웨어 TSL 명령 활용
- (중기) 커널 수준의 동기화 프리미티브(Mutex, Semaphore)를 활용한 안정적 구현
- (장기) 불변 자료구조 활용 및 메시지 패싱 기반 프로그래밍 모델 도입으로 공유 상태 제거

## Ⅵ. 전망
- 메모리 모델의 복잡성 증가로 인해 메모리 배리어(Memory Barrier)의 정확한 활용이 필수적임
- 고성능 컴퓨팅을 위해 락 경합을 줄이는 분산 자료구조와 낙관적 동기화(STM) 기술 확산 예상
