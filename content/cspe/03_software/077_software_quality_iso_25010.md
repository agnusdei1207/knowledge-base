## 미리 알고가기

- ISO/IEC 25010은 소프트웨어 품질 특성을 체계적으로 정리한 국제 표준임
- 품질 특성은 기능 적합성·성능 효율성·사용성·신뢰성·보안성·유지보수성 등의 상위 분류임
- 품질 속성을 수치와 테스트 기준으로 구체화해 요구·검증 기준으로 사용함

## 작성 근거(검토용)

- ISO/IEC 25010은 표현 방식, 요구·테스트 연결, 추상화 한계, 활용 단계를 핵심 비교축으로 선정함
- 구성과 절차는 품질 특성을 세부 특성·측정값·테스트 기준으로 구체화하는 흐름을 중심으로 제시함
- 실무 판단은 측정 가능 요구율, 모호한 인수 기준 수, 품질 우선순위 합의율로 구체화함

## Ⅰ. 개요

- **정의/개념**: ISO/IEC 25010은 소프트웨어 제품의 기능 적합성·성능 효율성·신뢰성·보안성·유지보수성 등을 구조화한 품질 모델임
- **배경/필요성**: 품질을 추상적으로 표현하면 요구·테스트·인수 해석이 달라지므로 이해관계자가 공유할 품질 분류와 측정 기준이 필요함

## Ⅱ. 특징

- 기능 품질과 비기능 품질을 하나의 분류 체계에서 다룸
- 요구 정의와 테스트 설계와 평가 보고서의 공통 기준이 됨
- 표준 특성을 그대로 적는 것만으로는 측정 가능성이 생기지 않음
- 도메인별 품질 우선순위와 합격 기준값을 함께 정의해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 비정형 품질 요구 | ISO/IEC 25010 기반 품질 모델 |
|:---|:---|:---|
| 표현 방식 | 조직별 용어로 품질을 설명함 | 공통 품질 특성 체계로 품질을 설명함 |
| 요구·테스트 연결 | 표현마다 별도 해석과 합의 필요 | 품질 특성·부특성별 측정값과 테스트 기준 연결 |
| 주요 한계 | 해석 차이가 커져 요구와 테스트가 어긋나기 쉬움 | 수치와 테스트 기준이 없으면 여전히 추상적으로 남을 수 있음 |
| 활용 단계 | 품질 요구 초안·예비 논의 | 공식 요구 명세·테스트 계획·평가 보고서 |

> 요약: 비정형 품질 요구는 해석이 달라질 수 있고 ISO/IEC 25010은 공통 특성과 측정 기준으로 연결함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 품질 특성 집합 | 기능과 성능과 보안과 유지보수처럼 큰 품질 영역을 체계적으로 분류함 |
| 세부 특성 매핑 | 각 품질 특성을 세부 항목으로 내려 실제 요구와 테스트 항목에 연결함 |
| 측정 기준 | 품질 특성을 응답 시간과 장애율 같은 수치 기준으로 바꿔 검증 가능하게 함 |
| 평가 맥락 | 도메인과 시스템 특성에 따라 어떤 품질을 우선할지 판단하게 함 |

> 요약: 도메인에 중요한 품질 특성을 세부 특성과 측정 기준으로 연결해 테스트 가능한 요구로 만듦.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 품질 특성 선택  | --> | 세부 항목 매핑 | --> | 측정 지표 정의 | --> | 테스트/평가 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **품질 특성 선택**: 업무 영향과 장애 비용을 기준으로 품질 특성을 선정함
2. **세부 항목 매핑**: 표준 특성을 도메인 언어로 구체화함
3. **측정 지표 정의**: 테스트 가능한 수치와 합격 기준을 정함
4. **테스트 및 평가 수행**: 결과를 품질 보고서와 인수 기준에 반영함

> 요약: 품질 특성을 도메인 요구로 구체화하고 측정값과 합격 기준을 정해 테스트·평가함.

## Ⅵ. 실무 사례

1. 공공 시스템은 품질 특성을 인수 기준값으로 구체화하고 측정 가능 요구율·모호한 기준 수를 확인함
2. 여러 부서가 쓰는 플랫폼은 품질 우선순위를 합의하고 합의율·재검토 건수를 확인함

## Ⅶ. 결론

ISO/IEC 25010은 추상적 품질 요구를 공통 품질 특성과 측정 가능한 테스트 기준으로 구체화함
