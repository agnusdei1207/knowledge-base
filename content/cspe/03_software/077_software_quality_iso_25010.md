## 미리 알고가기

- ISO/IEC 25010은 소프트웨어 품질 특성을 체계적으로 정리한 국제 표준임
- 품질 특성은 기능 적합성, 성능 효율성, 사용성, 신뢰성, 보안성, 유지보수성처럼 품질을 보는 큰 분류임
- 품질 속성은 수치 기준과 시험 기준으로 바뀌어야 실제 요구와 검증에 쓸 수 있음

## Ⅰ. 개요

- **정의/개념**: ISO/IEC 25010은 소프트웨어 제품 품질을 기능 적합성, 성능 효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성 같은 주요 특성으로 구조화한 품질 모델 표준임.
- **배경/필요성**: 품질을 빠르다, 안정적이다처럼 추상적으로만 표현하면 요구와 테스트와 인수 기준이 흔들리므로, 이해관계자가 공통으로 쓸 수 있는 품질 분류 체계가 필요함.

## Ⅱ. 특징

- 기능 품질과 비기능 품질을 같은 틀 안에서 다룰 수 있음
- 요구 정의와 테스트 설계와 평가 보고서의 공통 기준이 됨
- 표준 특성을 그대로 적는 것만으로는 측정 가능성이 생기지 않음
- 도메인별 우선순위와 수치 기준을 함께 정해야 실제 효과가 남음

## Ⅲ. 종류 및 비교

| 구분 | 비정형 품질 요구 | ISO/IEC 25010 기반 품질 모델 |
|:---|:---|:---|
| 표현 방식 | 팀이나 개인 언어로 품질을 설명함 | 공통 품질 특성 체계로 품질을 설명함 |
| 요구·시험 연결 | 표현마다 별도 해석과 합의 필요 | 품질 특성·부특성별 측정값과 시험 기준 연결 |
| 주요 한계 | 해석 차이가 커져 요구와 시험이 어긋나기 쉬움 | 수치와 시험 기준이 없으면 여전히 추상적으로 남을 수 있음 |
| 활용 단계 | 품질 요구 초안·예비 논의 | 공식 요구 명세·시험 계획·평가 보고서 |

> 요약: ISO/IEC 25010의 핵심은 품질 이름을 나열하는 데 있지 않고 품질 요구를 같은 언어로 정리하는 데 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 품질 특성 집합 | 기능과 성능과 보안과 유지보수처럼 큰 품질 영역을 체계적으로 분류함 |
| 세부 특성 매핑 | 각 품질 특성을 세부 항목으로 내려 실제 요구와 시험 항목에 연결함 |
| 측정 기준 | 품질 특성을 응답 시간과 장애율 같은 수치 기준으로 바꿔 검증 가능하게 함 |
| 평가 맥락 | 도메인과 시스템 특성에 따라 어떤 품질을 우선할지 판단하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 품질 특성 선택  | --> | 세부 항목 매핑 | --> | 측정 지표 정의 | --> | 시험/평가 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **품질 특성 선택**: 시스템에 중요한 품질 특성을 우선 선정함
2. **세부 항목 매핑**: 표준 특성을 도메인 언어로 구체화함
3. **측정 지표 정의**: 시험 가능한 수치와 합격 기준을 정함
4. **시험 및 평가 수행**: 결과를 품질 보고서와 인수 기준에 반영함

## Ⅵ. 실무 적용 및 유의점

1. 공공 시스템과 금융 플랫폼처럼 품질 설명 책임이 큰 환경에서는 ISO/IEC 25010이 유용하지만 특성만 선언하고 수치를 정하지 않으면 실효성이 약하므로 품질별 측정 기준을 함께 두고 측정 가능 요구 비율과 인수 기준 모호 문장 수로 확인함
2. 여러 부서가 같은 시스템을 검토하는 조직에서는 품질 우선순위가 자주 엇갈리므로 도메인별 우선순위를 먼저 합의하고 품질 우선순위 일치도와 리뷰 재설명 건수로 확인함

## Ⅶ. 결론

ISO/IEC 25010의 가치는 추상적 품질 요구를 공통 언어와 측정 가능한 기준으로 바꾸는 데 있음.
