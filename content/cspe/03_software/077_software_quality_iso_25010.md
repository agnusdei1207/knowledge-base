## 미리 알고가기

- ISO/IEC 25010은 소프트웨어 제품 품질 특성을 정의한 국제 표준 모델임
- 기능 적합성과 성능 효율성과 보안성과 유지보수성 등 품질 특성을 체계화함
- 품질 속성을 측정 가능한 기준으로 바꾸는 데 쓰인다

## Ⅰ. 개요

- **정의/개념**: ISO/IEC 25010은 소프트웨어 제품의 품질을 기능 적합성과 성능 효율성과 호환성과 사용성, 신뢰성, 보안성, 유지보수성, 이식성 등 주요 특성으로 구조화한 품질 모델 표준임
- **배경/필요성**: 품질을 추상적으로만 말하면 요구와 테스트와 인수 기준이 흔들리므로, 이해관계자가 공통으로 쓸 수 있는 품질 분류 체계가 필요함

## Ⅱ. 특징

- 품질을 기능과 비기능 전반의 체계적 특성으로 정리함
- 요구 정의와 테스트 설계와 평가 보고서의 공통 기준이 됨
- 표준 특성을 그대로 가져오는 것만으로는 측정 가능성이 생기지 않음
- 도메인별 품질 우선순위와 수치화 작업이 반드시 뒤따라야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 비정형 품질 요구 | ISO/IEC 25010 기반 품질 모델 |
|:---|:---|:---|
| 표현 방식 | 개별 팀 언어에 의존 | 공통 품질 특성 체계 사용 |
| 장점 | 빠른 작성 | 추적성과 비교 가능성 높음 |
| 한계 | 해석 차이 큼 | 수치화 없으면 추상적 |
| 활용 의미 | 임시 기준 | 공식 품질 요구와 평가 기준 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Quality Characteristic Set | 기능 적합성과 성능과 보안과 유지보수성 등 품질 영역을 체계적으로 분류함 |
| Sub-characteristic Mapping | 각 특성을 세부 항목으로 내려 실제 요구와 테스트 케이스에 연결함 |
| Measurement Criterion | 품질 특성을 응답시간과 결함률 같은 측정 지표로 바꾸어 검증 가능하게 함 |
| Evaluation Context | 도메인과 시스템 특성에 따라 어떤 품질 특성이 우선인지 결정하는 판단 기준이 됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 품질 특성 선택  | --> | 세부 항목 매핑 | --> | 측정 지표 정의 | --> | 시험/평가 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **품질 특성 선택**: 시스템에 중요한 품질 특성을 우선 선정함
2. **세부 항목 매핑**: 표준 특성을 도메인 언어로 구체화함
3. **측정 지표 정의**: 테스트 가능한 수치와 기준을 정함
4. **시험 및 평가 수행**: 결과를 품질 보고서와 인수 기준에 반영함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 품질 특성만 선언하고 측정 기준을 정의하지 않으면 표준이 있어도 실제 검증은 모호해질 수 있음
   - 해결방안: quality attribute별 KPI를 정의하고 measurable quality ratio와 acceptance ambiguity count로 검증함
2. 문제: 모든 특성을 동일 비중으로 다루면 핵심 시스템 품질 목표가 흐려질 수 있음
   - 해결방안: 도메인 우선순위를 명시하고 quality priority alignment와 test investment ratio로 검증함
3. 문제: 개발과 QA와 운영이 서로 다른 품질 언어를 쓰면 표준 모델도 현장에 정착하지 못할 수 있음
   - 해결방안: 공통 품질 사전을 운영하고 terminology consistency score와 review clarification count로 검증함

## Ⅶ. 적용 사례

- 공공 시스템 품질 명세에서는 ISO/IEC 25010을 사용하고, measurable quality ratio와 acceptance ambiguity count로 결과를 확인함
- 금융 플랫폼에서는 보안성과 신뢰성 우선순위를 명시하고, quality priority alignment와 defect escape rate로 결과를 확인함
- QA 조직 표준화에서는 품질 사전을 운영하고, terminology consistency score와 review clarification count로 결과를 확인함

## Ⅷ. 결론

ISO/IEC 25010의 가치는 품질 이름을 많이 붙이는 데 있지 않고 추상적 품질 요구를 공통 언어와 측정 가능한 기준으로 바꾸는 데 있음.
