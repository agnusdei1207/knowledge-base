## Ⅰ. 개요
- 정의: API 게이트웨이는 시스템 단일 진입점, 서비스 디스커버리는 유동적인 서비스 위치를 찾는 기술.
- 출제 의도: MSA 환경에서 서비스 연결 및 공통 기능 처리를 위한 핵심 인프라 기술 이해도 측정.

## Ⅱ. 구성요소
- ASCII 구조도
  [ Client ] -> [ API Gateway ] <---> [ Service Discovery (Consul) ]
                   |                           ^ (Register)
            [ Service A (v1) ] [ Service B (v2) ]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| API Gateway | 인증, 라우팅, 속도 제한 등 공통 기능을 처리하는 게이트 | 공항 보안 검색대 |
| Service Registry | 모든 서비스 인스턴스의 네트워크 위치 정보를 저장하는 DB | 전화번호부 |
| Health Check | 각 서비스의 생존 여부를 주기적으로 확인하여 가용성 유지 | 출석 체크 |
> 요약: 게이트웨이가 디스커버리에서 위치를 조회하여 요청을 전달하는 유기적 관계임.

## Ⅲ. 절차
- ASCII 흐름도
  [서비스 기동/등록] -> [클라이언트 요청] -> [위치 조회] -> [라우팅/전달]
- 4단계 설명
1. 신규 서비스 인스턴스 기동 시 자신의 IP/Port를 레지스트리에 자동 등록함.
2. 클라이언트가 API Gateway에 특정 API 호출 요청을 보냄.
3. 게이트웨이는 레지스트리에서 해당 서비스의 유효한 주소를 조회함.
4. 로드밸런싱 알고리즘에 따라 최적의 인스턴스로 요청을 포워딩함.
> 요약: 동적으로 변하는 분산 환경에서 투명한 통신 경로를 제공함.

## Ⅳ. 문제점
- SPOF 위험: API Gateway 장애 시 전체 시스템 접근이 차단됨.
- 네트워크 홉 추가: 추가적인 네트워크 계층 통과로 인해 지연 시간(Latency) 소폭 증가함.

## Ⅴ. 개선방안
- Gateway 다중화: 여러 대의 게이트웨이를 배치하고 L4 로드밸런서로 부하 분산함.
- 클라이언트 사이드 디스커버리: 클라이언트가 직접 레지스트리 조회하여 성능 오버헤드 완화함.

## Ⅵ. 전망
- 클라우드 네이티브 게이트웨이(Envoy 기반) 기술이 표준으로 자리 잡으며 성능 고도화됨.
- 보안 기능(WAF, DDoS 방어)이 내재화된 통합 API 관리 플랫폼(APIM) 형태로 진화할 것임.
- gRPC, GraphQL 등 다양한 프로토콜을 동시에 지원하는 멀티 프로토콜 게이트웨이 수요 증대됨.
