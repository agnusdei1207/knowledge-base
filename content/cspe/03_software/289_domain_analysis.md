## Ⅰ. 개요
- 정의: 특정 영역 내 공통점과 차이점을 식별하여 재사용 가능한 자산으로 추상화하는 활동임
- 배경: 소프트웨어 재사용성 극대화 및 비즈니스 도메인 지식의 자산화 필요성 증대
- 출제 의도: 도메인 공통/가변성 식별 및 제품군(Product Line) 기반 구축 역량 평가

## Ⅱ. 구성요소
- ASCII 구조도
  [Domain Expert] -> [Analysis] -> [Domain Model]
                          |             |
                  [Commonalities] [Variabilities]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 도메인 지식 | 특정 산업/영역의 전문 지식 및 용어 | 설계 도면 |
| 공통성(Common) | 도메인 내 모든 시스템에 공통된 특성 | 표준 부품 |
| 가변성(Variable)| 시스템마다 달라지는 선택적 특성 | 옵션 부품 |
> 요약: 전문 지식을 바탕으로 표준화된 공통 요소와 선택적 요소를 분리 모델링함

## Ⅲ. 절차
- ASCII 흐름도
  Scoping -> Analysis -> Modeling -> Verification
- 4단계 설명
1. Scoping: 분석 대상 도메인의 경계 확정 및 대상 시스템 선정함
2. Analysis: 도메인 용어 사전 구축 및 공통/가변 속성 식별함
3. Modeling: 피처 모델(Feature Model), 객체 모델 등으로 가시화함
4. Verification: 도메인 전문가 검토를 통한 모델의 정확성 검증함
> 요약: 범위 확정 후 공통/가변 특성을 도출하여 검증된 모델로 변환함

## Ⅳ. 문제점
- 원인이 명시된 문제/한계: 전문가 의존도 심화로 인한 지식 편중 및 병목 현상 발생함

## Ⅴ. 개선방안
- Ⅳ의 문제에 대응하는 방안: 지식 베이스(KB) 자동화 도구 도입 및 표준 온톨로지 구축함

## Ⅵ. 전망
- 발전 방향: 생성형 AI 연계 도메인 지식 자동 추출 및 동적 모델링 기술 확산 전망
- CSF: 도메인 전문가와 엔지니어 간의 원활한 소통을 위한 공통 언어(Ubiquitous Language) 확보가 핵심임
