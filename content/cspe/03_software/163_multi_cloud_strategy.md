## 미리 알고가기

- 멀티 클라우드는 둘 이상의 퍼블릭 클라우드 공급자를 업무별로 병행하는 구성임
- 분할 배치는 애플리케이션이나 데이터 처리 단위를 공급자별로 나누는 방식임
- 중복 배치는 같은 서비스를 여러 공급자에 두고 장애 전환에 사용하는 방식임
- 이식성(포터빌리티)은 실행 패키지·배포 선언·데이터 형식을 다른 환경으로 옮길 수 있는 정도임
- 이그레스 비용은 클라우드 외부나 다른 공급자로 데이터를 전송할 때 발생하는 비용임
- 공통 거버넌스는 계정·권한·정책·비용·관측 기준을 공급자마다 일관되게 적용하는 체계임
- IaC·CI/CD는 환경별 인프라와 배포 절차를 코드로 반복 적용함

## 작성 근거(검토용)

- 멀티 클라우드는 공급자 수가 아니라 업무 배치와 공통 통제 방식이 핵심이므로 분할·중복 전략을 대비함
- 데이터 이동·상태 동기화·장애 분리를 비교표의 핵심 판단축으로 삼고 이식성·운영 통제는 Ⅳ 구성요소와 결론에서 다룸
- Ⅴ절은 요구 분류부터 공급자 선택·배치·공통 통제·전환 검증까지의 적용 절차로 구성함
- 제목부터 결론까지 5회 전수 검수하여 공급자 분산의 효과와 운영 비용을 함께 확인함

## Ⅰ. 개요

- **정의/개념**: 멀티 클라우드 전략은 둘 이상의 퍼블릭 클라우드에 워크로드를 분할하거나 중복 배치하고 공통 정책으로 운영하는 방식임
- **배경/필요성**: 공급자별 관리 서비스 활용과 장애 영역 분리를 위해 워크로드 배치·이식·통제 기준이 필요함

### 쉽게 이해하기 (학습용)
- 멀티 클라우드는 여러 공급자를 쓰는 사실보다 업무를 왜 나누고 어떻게 함께 통제할지가 핵심임

## Ⅱ. 특징

- 워크로드 요구와 공급자 서비스 특성을 대조해 실행 위치를 결정함
- 계정·권한·배포·관측·비용 데이터를 공급자별 API에서 공통 기준으로 수집함
- 컨테이너와 IaC는 실행·배포 형식을 맞추지만 관리 서비스 차이까지 제거하지는 못함
- 중복 배치는 한 공급자의 장애 시 다른 공급자로 전환할 수 있지만 데이터 복제·이그레스·운영 도구 중복 비용이 추가됨

### 쉽게 이해하기 (학습용)
- 공급자 선택과 장애 분리의 이점은 데이터 이동과 중복 운영 부담을 함께 감수할 때 얻을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 분할 멀티 클라우드 | 중복 멀티 클라우드 |
|:---|:---|:---|
| 배치 단위 | 업무·계층·데이터 처리별로 공급자를 선택 | 같은 서비스 인스턴스를 여러 공급자에 배치 |
| 데이터 흐름 | 업무 경계를 넘을 때 공급자 간 데이터가 이동하며 소유권을 분리 관리 | 복제·동기화로 상태를 맞추고 지연·쓰기 충돌 기준을 관리 |
| 장애 대비 | 업무별 대체 경로를 별도로 설계 | 정상 공급자의 중복 인스턴스로 전환 |

> 요약: 분할 전략은 업무 경계별 배치와 데이터 이동이, 중복 전략은 복제 기반 장애 전환이 중심임.

### 쉽게 이해하기 (학습용)
- 분할은 일을 나누어 맡기고 중복은 같은 일을 둘 이상이 대신할 수 있게 준비하는 방식임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 역할 |
|:---|:---|
| 배치 정책 | 지연·데이터 위치·관리 서비스·비용으로 공급자를 선택함 |
| 공통 ID·권한 | 조직 계정과 역할을 공급자별 권한 모델에 연결함 |
| 배포 계층 | IaC·CI/CD·이미지 정책으로 환경별 배포 차이를 통제함 |
| 연결·데이터 계층 | 공급자 간 라우팅·복제·암호화·이그레스 경로를 관리함 |
| 통합 관측 | 로그·메트릭·추적 식별자로 공급자 간 요청 경로를 추적함 |
| 거버넌스·비용 통제 | 태그·예산·구성 정책 위반을 공급자 공통 거버넌스로 판정함 |

```text
                     +-> 클라우드 A -> 업무 A
공통 정책·배포·관측 -+-> 클라우드 B -> 업무 B
                     +-> 클라우드 C -> 중복 서비스
```

> 요약: 워크로드는 공급자별로 배치하되 정책·배포·관측 정보는 공통 통제 계층에 모음.

### 쉽게 이해하기 (학습용)
- 실행 환경은 달라도 계정·배포·로그·비용을 한 기준으로 묶어야 전체 상태를 판단할 수 있음

## Ⅴ. 원리 및 절차 흐름도

```text
업무 요구 분류 -> 공급자·배치 전략 선택 -> 연결·데이터 설계 -> 공통 통제 적용 -> 전환 검증
```

1. 업무별 지연·데이터 위치·가용성·관리 서비스 요구를 분류함
2. 공급자별 강점과 종속성을 비교해 분할 또는 중복 배치를 선택함
3. 공급자 간 네트워크·복제·암호화·이그레스 경로를 설계함
4. ID·IaC·배포·관측·비용 정책을 공통 기준으로 적용함
5. 장애 전환·복제 지연·데이터 이동 비용을 검증하고 배치를 조정함

> 요약: 업무 요구로 공급자와 배치 방식을 정하고 공통 통제와 전환 시험으로 효과를 확인함.

### 쉽게 이해하기 (학습용)
- 공급자를 고른 뒤 업무 분담표와 공통 운영 규칙을 만들고 실제 대체 가능성을 시험함

## Ⅵ. 실무 사례

1. 분석 파이프라인은 수집·처리를 공급자별 관리 서비스에 분할하고 이그레스 비용·처리 지연을 확인함
2. 인증 API는 두 공급자에 중복 배치하고 장애 전환 시간·복제 지연을 확인함

### 쉽게 이해하기 (학습용)
- 분석 업무의 분할과 인증 서비스의 중복은 목표가 달라 각각 비용과 장애 전환 지표를 봐야 함

## Ⅶ. 결론

- 멀티 클라우드는 공급자별 서비스 선택이나 장애 분리 효과가 데이터 이동·운영 중복 비용보다 클 때 적용해야 함

### 쉽게 이해하기 (학습용)
- 공급자를 늘리는 것 자체보다 얻는 효과가 연결과 중복 관리 비용을 넘는지가 판단 기준임
