## Ⅰ. 개요
- 정의: 시스템의 보안 취약점을 식별하고 자산 보호 능력을 검증하는 활동
- 배경: 지능화된 사이버 공격 증가 및 개인정보 보호 법규 준수 요건 강화
- 출제 의도: 정적/동적 보안 분석 기법(SAST, DAST) 및 모의해킹 이해

## Ⅱ. 구성요소
- 구조도
  [White Box] : SAST (Code Analysis)
  [Black Box] : DAST (Fuzzing, Scanning)
  [Manual]    : Pen-Testing (Expert Attack)

- 구성요소 표
| 구분 | 설명 | 대표 항목 |
| :--- | :--- | :--- |
| SAST | 소스 코드 내 취약 패턴 분석 | SQL Injection, XSS 패턴 |
| DAST | 실행 중인 웹 앱에 공격 시뮬레이션 | 인증 우회, 세션 가로채기 |
| 모의해킹 | 전문가가 해커 관점에서 직접 침투 | 시나리오 기반 공격 |
> 요약: SAST는 코드 패턴, DAST는 실행 환경의 공격 반응, 모의해킹은 시나리오 기반 침투 가능성을 검증함

## Ⅲ. 절차
- 흐름도
  정보 수집 -> 취약점 분석 -> 침투 시도 -> 결과 보고/조치
- 4단계 설명
1. 정보 수집: 대상 시스템의 OS, 포트, 서비스 정보 등 자산 현황 파악
2. 취약점 분석: 자동화 스캐너 및 수동 점검을 통해 알려진 취약점 식별
3. 침투 시도: 식별된 취약점을 활용하여 실제 시스템 권한 획득 가능성 검증
4. 결과 보고/조치: 자산 영향·공격 가능성·증거를 기준으로 심각도를 산정하고 조치 방안 제시
> 요약: 자산 정보를 수집하고 취약점을 식별·검증하여 재현 증거와 조치 우선순위를 기록함

## Ⅳ. 문제점
- 자동화 스캐너에만 의존할 경우 복합적인 비즈니스 로직 취약점 탐지 불가
- 보안 점검 중 시스템 장애 발생 우려로 인해 운영 환경에서의 실효성 있는 테스트 제약

## Ⅴ. 개선방안
- 개발 초기 단계부터 보안을 고려하는 DevSecOps 체계 및 보안 코딩 준수
- 스테이징 환경에서 실제 데이터가 아닌 마스킹된 데이터를 활용한 모의 침투 실시

## Ⅵ. 전망
- 클라우드 설정 오류 자동 탐지(CSPM) 및 API 보안 테스팅 영역의 중요도 급증
- CSF: 정기적인 점검을 넘어 실시간 보안 관제 및 위협 인텔리전스 공유 체계 강화
