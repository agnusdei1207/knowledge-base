## 미리 알고가기

- SQL은 관계형 데이터베이스의 구조를 만들고 데이터를 다루고 권한을 통제하는 표준 언어임
- DDL은 구조 정의, DML은 데이터 조회와 변경, DCL은 권한 부여와 회수를 담당함
- 같은 SQL이라도 구조 변경과 데이터 변경과 권한 변경은 운영 위험이 서로 다름

## Ⅰ. 개요

- **정의/개념**: SQL 기본 분류에서 DDL은 테이블과 인덱스와 제약조건 같은 구조를 정의하고, DML은 데이터를 조회하고 삽입하고 수정하고 삭제하며, DCL은 사용자 권한과 접근 범위를 관리하는 관계형 데이터베이스 언어 체계임.
- **배경/필요성**: 스키마 변경과 데이터 변경과 권한 변경은 영향 범위와 복구 방식이 다르므로, 같은 SQL이라도 목적에 따라 구분해 다뤄야 운영 사고를 줄일 수 있음.

## Ⅱ. 특징

- 원하는 결과를 선언적으로 표현하지만 실행 영향은 매우 구체적임
- DDL과 DML과 DCL은 목적이 다르므로 승인 절차와 검증 기준도 달라야 함
- 구문을 아는 것보다 어떤 변경이 어떤 범위에 영향을 주는지 이해하는 것이 중요함
- 잘못 실행하면 데이터 손상과 서비스 중단과 과권한 노출이 바로 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | DDL | DML | DCL |
|:---|:---|:---|:---|
| 주 목적 | 테이블과 인덱스와 제약조건을 만들고 바꿈 | 데이터를 조회하고 바꾸고 지움 | 사용자 권한을 주고 회수함 |
| 대표 명령 | CREATE, ALTER, DROP | SELECT, INSERT, UPDATE, DELETE | GRANT, REVOKE |
| 주요 위험 | 스키마 파괴와 호환성 문제 | 대량 오수정과 정합성 저하 | 과권한과 비인가 접근 |
| 운영 기준 | 변경 검토와 배포 절차가 필수임 | 트랜잭션과 대상 검증이 중요함 | 최소 권한과 변경 이력 관리가 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 구조 정의 문장 | 테이블과 인덱스와 제약조건을 선언해 저장 구조를 만듦 |
| 데이터 조작 문장 | 업무 데이터를 읽고 바꾸어 서비스 기능을 수행함 |
| 권한 통제 문장 | 사용자와 역할에 접근 권한을 부여하거나 회수함 |
| 변경 관리 절차 | 실행 전 검토와 승인과 롤백 계획으로 운영 위험을 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 성격 구분  | --> | SQL 작성      | --> | 영향 검토       | --> | 실행 후 검증    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 성격 구분**: 구조 변경인지 데이터 조작인지 권한 제어인지 먼저 구분함
2. **SQL 작성**: 목적에 맞는 문장을 작성함
3. **영향 검토**: 대상 범위와 복구 방법과 권한 영향을 점검함
4. **실행 후 검증**: 실제 반영 결과와 부작용을 확인함

## Ⅵ. 실무 적용 및 유의점

1. 운영 배포에서 DDL은 구조를 직접 바꾸므로 사전 검토와 롤백 계획을 반드시 두고 변경 실패율과 롤백 성공률로 확인함.
2. 대량 DML과 권한 변경은 범위를 잘못 잡으면 즉시 장애나 보안 사고로 이어지므로 실행 전 대상 건수와 권한 범위를 검증하고 의도하지 않은 변경 건수와 과권한 계정 수로 확인함.

## Ⅶ. 결론

SQL의 DDL과 DML과 DCL 구분은 문법 암기용 분류가 아니라 구조와 데이터와 권한 변경의 위험을 서로 다르게 통제하기 위한 운영 기준임.
