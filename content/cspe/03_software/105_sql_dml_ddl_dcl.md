## 미리 알고가기

- SQL은 관계형 데이터베이스의 구조를 만들고 데이터를 다루고 권한을 통제하는 표준 언어임
- DDL은 구조 정의, DML은 데이터 조회와 변경, DCL은 권한 부여와 회수를 담당함
- 같은 SQL이라도 구조 변경과 데이터 변경과 권한 변경은 운영 위험이 서로 다름

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- SQL은 DDL·DML·DCL의 목적과 변경 대상을 핵심 축으로 설명함
- 비교표는 대표 명령·주요 위험·운영 검증 기준을 대비함
- 운영 DB는 변경 실패율·과권한 계정 수로 검증함

## Ⅰ. 개요

- **정의/개념**: SQL에서 DDL은 데이터 구조, DML은 데이터 조회·변경, DCL은 사용자 권한을 정의·통제하는 명령 체계임
- **배경/필요성**: 구조·데이터·권한 변경의 영향 범위와 복구 방식을 구분해 운영 위험을 통제하기 위해 SQL 명령 분류가 필요함

## Ⅱ. 특징

- SQL은 처리 절차가 아닌 원하는 결과를 선언함
- DDL과 DML과 DCL은 목적이 다르므로 승인 절차와 검증 기준도 달라야 함
- DDL은 구조 호환성과 의존 객체, DML은 대상 행과 트랜잭션, DCL은 권한 범위를 검증함
- 변경 범위를 잘못 지정하면 서비스 중단·데이터 오수정·과권한이 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | DDL | DML | DCL |
|:---|:---|:---|:---|
| 주 목적 | 테이블과 인덱스와 제약조건을 만들고 바꿈 | 데이터를 조회하고 바꾸고 지움 | 사용자 권한을 주고 회수함 |
| 대표 명령 | CREATE, ALTER, DROP | SELECT, INSERT, UPDATE, DELETE | GRANT, REVOKE |
| 주요 위험 | 스키마 파괴와 호환성 문제 | 대량 오수정과 정합성 저하 | 과권한과 비인가 접근 |
| 운영 검증 | 의존 객체·락·롤백 경로 확인 | 대상 행 수·조건·커밋 범위 확인 | 주체·객체·권한·회수 이력 확인 |

> 요약: DDL은 구조, DML은 데이터, DCL은 권한을 변경하므로 대상과 운영 위험이 서로 다름.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 구조 정의 문장 | 테이블과 인덱스와 제약조건을 선언해 저장 구조를 만듦 |
| 데이터 조작 문장 | 업무 데이터를 읽고 바꾸어 서비스 기능을 수행함 |
| 권한 통제 문장 | 사용자와 역할에 접근 권한을 부여하거나 회수함 |
| 변경 관리 절차 | 실행 전 검토와 승인과 롤백 계획으로 운영 위험을 줄임 |

> 요약: 구조 정의·데이터 조작·권한 통제 문장을 변경 목적에 맞게 구분하고 실행 위험을 관리함.

## Ⅵ. 실무 사례

1. 운영 스키마 배포는 DDL의 의존 객체와 락을 검토하고 변경 실패율·락 대기 시간을 확인함
2. 서비스 계정은 DCL로 역할과 회수 기한을 설정하고 과권한 계정 수·권한 회수 시간을 확인함

## Ⅶ. 결론

- DDL·DML·DCL은 구조·데이터·권한 변경의 목적과 운영 위험을 구분하는 SQL 분류임
