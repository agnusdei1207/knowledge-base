## 미리 알고가기

- B-Tree는 페이지 안에서 키를 정렬해 두고 그 상태를 유지하며 읽고 쓰는 균형 트리 구조임
- LSM-Tree는 메모리에 먼저 쓰고 디스크에는 정렬된 파일을 쌓아 두었다가 나중에 병합하는 구조임
- SSTable은 정렬된 불변 파일이고, Bloom Filter는 없는 키를 빠르게 걸러 주는 보조 구조임

## Ⅰ. 개요

- **정의/개념**: B-Tree와 LSM-Tree는 키 기반 저장 엔진의 대표 구조로서 B-Tree는 균형 트리에서 제자리 탐색과 갱신을 수행하고, LSM-Tree는 메모리와 디스크에 정렬된 파일을 단계적으로 쌓은 뒤 병합해 쓰기 효율을 높이는 저장 방식임.
- **배경/필요성**: 읽기 지연이 중요한지 쓰기 처리량이 중요한지에 따라 저장 엔진의 병목이 달라지므로, 데이터베이스 구조 선택이 전체 성능과 운영 비용을 크게 좌우함.

## Ⅱ. 특징

- B-Tree는 점 조회와 범위 조회의 지연이 비교적 안정적임
- LSM-Tree는 순차 쓰기에 강해 대량 적재와 쓰기 집약 업무에 유리함
- B-Tree는 랜덤 쓰기와 페이지 분할 비용이 누적될 수 있음
- LSM-Tree는 병합 작업과 읽기 증폭과 공간 증폭을 꾸준히 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | B-Tree | LSM-Tree |
|:---|:---|:---|
| 쓰기 방식 | 페이지를 찾아 제자리에서 갱신함 | 메모리에 먼저 기록한 뒤 디스크 파일로 내려 쓰고 병합함 |
| 읽기 특성 | 점 조회와 범위 조회가 안정적임 | 보조 구조가 없으면 여러 파일을 함께 확인할 수 있음 |
| 운영 부담 | 분할과 조각화 관리가 필요함 | 병합 작업과 증폭 비용 관리가 필요함 |
| 잘 맞는 업무 | 읽기 지연이 중요한 일반 온라인 트랜잭션 처리 | 쓰기 집약 로그와 시계열과 대량 적재 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 쓰기 경로 | B-Tree는 페이지 갱신을 하고 LSM-Tree는 메모리 테이블과 디스크 파일 생성을 거침 |
| 읽기 경로 | B-Tree는 트리 탐색으로 끝나고 LSM-Tree는 여러 레벨과 보조 필터를 확인할 수 있음 |
| 유지 작업 | B-Tree는 분할과 재균형을, LSM-Tree는 병합과 압축을 반복함 |
| 증폭 지표 | 읽기 증폭과 쓰기 증폭과 공간 증폭이 장기 운영 비용을 보여 줌 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 워크로드 분석   | --> | 저장 구조 선택  | --> | 읽기/쓰기 운영  | --> | 증폭 비용 검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **워크로드 분석**: 읽기와 쓰기 비율과 범위 조회 빈도를 확인함
2. **저장 구조 선택**: B-Tree와 LSM-Tree 중 더 적합한 구조를 고름
3. **읽기와 쓰기 운영**: 각 구조에 맞게 인덱스와 병합 정책을 조정함
4. **증폭 비용 검증**: 읽기와 쓰기와 저장 공간의 장기 비용을 측정함

## Ⅵ. 실무 적용 및 유의점

1. 로그 수집과 시계열 적재처럼 쓰기 처리량이 중요한 환경에서는 LSM-Tree가 유리하지만 병합 작업이 몰리면 지연이 튈 수 있으므로 병합 대기 시간과 쓰기 처리량으로 확인함.
2. 사용자 조회와 범위 검색처럼 지연 예측이 중요한 업무에서는 B-Tree가 유리하지만 쓰기 편중 시 분할 비용이 커질 수 있으므로 페이지 분할률과 상위 99% 조회 지연 시간으로 확인함.

## Ⅶ. 결론

B-Tree와 LSM-Tree 선택의 기준은 유행이 아니라 읽기 지연 안정성과 쓰기 처리량 중 무엇을 더 우선하는지에 달려 있음.
