## 미리 알고가기

- B-Tree는 페이지 안에서 키를 정렬해 두고 그 상태를 유지하며 읽고 쓰는 균형 트리 구조임
- LSM-Tree는 메모리에 먼저 쓰고 디스크에는 정렬된 파일을 쌓아 두었다가 나중에 병합하는 구조임
- SSTable은 정렬된 불변 파일이고, Bloom Filter는 없는 키를 사전에 제외하는 보조 구조임
- 증폭은 사용자 요청보다 실제 읽기·쓰기·저장 작업이 더 많이 발생하는 비율이며 두 구조의 운영 비용을 비교하는 지표임

## 작성 근거(검토용)

- 제목·frontmatter·미리 알고가기·본문·표·요약·결론을 5회 전수 검수해 어색한 단어·조사·동사 결합·장황한 명사구를 교정함
- B-Tree와 LSM-Tree는 읽기·쓰기 경로와 증폭 비용을 핵심 축으로 설명함
- 비교표는 쓰기 방식·읽기 경로·운영 선택을 대비함
- 저장 엔진은 p99 읽기 지연·쓰기 처리량으로 검증함

## Ⅰ. 개요

- **정의/개념**: B-Tree는 균형 트리의 페이지를 직접 갱신하고, LSM-Tree는 메모리에 쓴 데이터를 정렬 파일로 내린 뒤 병합하는 키 기반 저장 구조임
- **배경/필요성**: 읽기 지연·쓰기 처리량·증폭 비용의 우선순위에 맞는 저장 엔진을 선택하기 위해 두 구조의 데이터 경로를 구분해야 함

### 쉽게 이해하기 (학습용)
- B-Tree는 정리된 장부를 즉시 고치고, LSM-Tree는 메모지에 모아 적은 뒤 장부 묶음을 나중에 합침

## Ⅱ. 특징

- B-Tree는 점 조회와 범위 조회의 지연이 비교적 안정적임
- LSM-Tree는 memtable 기록 후 immutable SSTable을 순차 생성하고 compaction으로 병합함
- B-Tree는 랜덤 쓰기와 페이지 분할 비용이 누적될 수 있음
- LSM-Tree는 병합 작업과 읽기 증폭과 공간 증폭을 꾸준히 관리해야 함

### 쉽게 이해하기 (학습용)
- 즉시 정리하면 읽기 쉽고, 나중에 몰아 정리하면 쓰기는 빠르지만 병합 작업이 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | B-Tree | LSM-Tree |
|:---|:---|:---|
| 쓰기 방식 | 페이지를 찾아 제자리에서 갱신함 | 메모리에 먼저 기록한 뒤 디스크 파일로 내려 쓰고 병합함 |
| 읽기 경로 | 루트에서 리프 페이지까지 탐색함 | 메모리와 여러 SSTable을 탐색할 수 있음 |
| 운영 선택 | 읽기 지연이 엄격한 온라인 거래에 적합함 | 쓰기 집약 로그·시계열에서 컴팩션과 증폭을 관리함 |

> 요약: B-Tree는 페이지 직접 갱신과 점·범위 조회에, LSM-Tree는 메모리·SSTable 쓰기와 높은 쓰기 처리량에 적합함.

### 쉽게 이해하기 (학습용)
- B-Tree는 안정적인 읽기, LSM-Tree는 높은 쓰기 처리량을 우선할 때 선택함

## Ⅳ. 설계 요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 쓰기 경로 | B-Tree는 페이지 갱신을 하고 LSM-Tree는 메모리 테이블과 디스크 파일 생성을 거침 |
| 읽기 경로 | B-Tree는 루트에서 리프 페이지를 탐색하고 LSM-Tree는 여러 레벨과 보조 필터를 확인함 |
| 유지 작업 | B-Tree는 분할과 재균형을, LSM-Tree는 병합과 압축을 반복함 |
| 증폭 지표 | 읽기 증폭과 쓰기 증폭과 공간 증폭이 장기 운영 비용을 보여 줌 |

> 요약: 두 구조는 쓰기·읽기·유지 작업 경로가 다르며 읽기·쓰기·공간 증폭으로 운영 비용을 비교함.

### 쉽게 이해하기 (학습용)
- 자료를 고치는 경로, 찾는 경로, 정리 작업과 실제 추가 수고를 묶어 비교함

## Ⅴ. 원리 및 절차 흐름도

```text
B-Tree:  [루트 탐색] -> [리프 갱신] -> [분할·재균형]
LSM-Tree:[Memtable 기록] -> [SSTable 생성] -> [Compaction]
```

1. **B-Tree 쓰기**: 루트 탐색 → 리프 페이지 확인 → 키 삽입·갱신 → 필요 시 페이지 분할·재균형 순으로 처리함
2. **LSM-Tree 쓰기**: 로그·메모리 테이블 기록 → 불변 메모리 테이블 전환 → SSTable 저장 → 컴팩션 순으로 처리함

> 요약: B-Tree는 리프 페이지를 직접 갱신하고, LSM-Tree는 메모리 기록을 SSTable로 저장한 뒤 컴팩션함.

### 쉽게 이해하기 (학습용)
- B-Tree는 해당 장부 쪽을 바로 고치고 LSM-Tree는 메모지를 파일로 내려 쓴 뒤 파일들을 합침

## Ⅵ. 실무 사례

1. 로그 저장소는 LSM-Tree의 컴팩션 정책을 조정하고 쓰기 처리량·컴팩션 대기 시간을 확인함
2. 사용자 조회 DB는 B-Tree를 적용하고 p99 조회 지연·페이지 분할률을 확인함

### 쉽게 이해하기 (학습용)
- 로그는 빠르게 쌓는 구조를, 거래 조회는 일정하게 찾는 구조를 우선 검토함

## Ⅶ. 결론

- B-Tree와 LSM-Tree는 읽기 지연·쓰기 처리량·증폭 비용의 우선순위에 따라 선택함
- 평균 성능만 보지 말고 p99 지연·컴팩션 정체·쓰기·공간 증폭을 장기 관찰해 저장 엔진을 조정해야 함

### 쉽게 이해하기 (학습용)
- 처음 속도뿐 아니라 장부가 쌓인 뒤 정리 비용과 최악의 지연까지 보고 선택해야 함
