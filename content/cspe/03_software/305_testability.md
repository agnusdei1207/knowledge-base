## Ⅰ. 개요
- 정의: 입력과 상태를 제어하고 내부 동작과 결과를 관찰하여 결함을 재현·격리할 수 있게 설계하는 특성임
- 배경: 소프트웨어 복잡도 증가에 따른 테스트 비용 상승 및 품질 검증 한계 극복 필요
- 출제 의도: 제어 가능성(Controllability) 및 관찰 가능성(Observability) 확보 전략 평가

## Ⅱ. 구성요소
- ASCII 구조도
  [Input] -> [Interface] -> [Target Module] -> [Output]
      ^                         |                |
  (Control)                 (Monitor)        (Observe)
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 제어 가능성 | 특정 상태나 입력으로 시스템을 유도하기 쉬운 정도 | 조종 장치 |
| 관찰 가능성 | 내부 상태 및 수행 결과를 외부에서 확인하기 쉬운 정도 | 계기판 |
| 관심사 분리 | 기능을 독립적으로 테스트 가능하도록 격리함 | 부품별 검사 |
> 요약: 입력 제어와 결과 관찰이 용이하도록 모듈 간 독립성을 확보하는 설계임

## Ⅲ. 절차
- ASCII 흐름도
  Interface Design -> Injection Point -> Logging -> Mocking
- 4단계 설명
1. Interface Design: 외부에서 내부 로직에 접근 가능한 명확한 통로 정의함
2. Injection Point: 의존성 주입(DI) 등을 통해 테스트 데이터 주입 지점 확보함
3. Logging: 수행 단계별 상태 변화를 추적할 수 있는 상세 로그 설계함
4. Mocking: 외부 연동 시스템을 가상화하여 독립적 테스트 환경 구성함
> 요약: 인터페이스와 로그를 설계하고 의존성 관리를 통해 독립 테스트를 지원함

## Ⅳ. 문제점
- 테스트 전용 인터페이스·로그·대역 객체가 과도하면 제품 코드와 테스트 자산의 변경 비용이 함께 증가함

## Ⅴ. 개선방안
- 위험도가 높은 모듈부터 제어·관찰 지점을 설계하고 공통 테스트 픽스처와 자동화 도구를 재사용함

## Ⅵ. 전망
- 발전 방향: AI 기반 자동 테스트 케이스 생성 및 런타임 자가 진단 아키텍처 부각
- CSF: 설계 초기부터 테스트 시나리오를 고려하는 'Test-first' 마인드셋 확립이 필수임
