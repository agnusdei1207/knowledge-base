# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 정규화된 데이터베이스에서 성능 향상과 개발 편의성을 위해 데이터 중복을 허용하는 설계 기법이다.
- **왜 필요한가**: 과도한 조인(Join) 연산으로 인한 디스크 I/O 증가와 조회 응답 시간 지연을 해결하기 위해 필요하다.
- **핵심 직관**: 읽기 속도를 높이기 위해 쓰기 정합성(이상 현상 위험)과 저장 공간을 지불하는 성능 거래다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 정규화 (Normalization) | 데이터 중복을 최소화하도록 테이블을 쪼개는 과정 | 짐을 종류별로 여러 서랍에 완벽히 나눠 담는 것 |
| 조인 (Join) | 쪼개진 여러 테이블에서 데이터를 다시 연결해 가져오는 연산 | 여러 서랍을 열고 닫으며 필요한 물건을 모으는 것 |
| 데이터 정합성 (Data Consistency) | 데이터가 모순 없이 일관되게 유지되는 상태 | 주소가 바뀌었을 때 모든 명부의 주소가 똑같이 바뀌어 있는 것 |

## 깊이 이해
- **배경·문제의식**: 높은 정규화는 데이터 정합성을 보장하지만, 복잡한 조회 시 테이블 3~4개를 조인해야 한다. 이는 대량 트래픽 환경에서 디스크 I/O를 급증시켜 심각한 응답 지연을 초래한다.
- **작동 원리**: 자주 같이 조회되는 데이터를 하나의 테이블에 합치거나, 요약/집계 데이터를 별도 컬럼으로 미리 계산해 저장한다. 읽기 시 조인 없이 단일 테이블에서 데이터를 즉시 반환한다.
- **비유**: 매번 요리할 때마다 밀가루, 소금, 버터를 꺼내 반죽(조인) 대신, 미리 만들어진 냉동 생지를 굽는 것.
- **구체 예시**: `주문` 테이블과 `고객` 테이블 조인을 피하기 위해 `주문` 테이블에 `고객명` 컬럼을 중복해서 저장한다.
- **흔한 오해·주의점**: 완벽한 정규화(보통 3NF)를 마친 논리적 모델링 위에서, 물리적 성능 한계를 극복하기 위해 전략적으로 일부를 뭉치는 후행 작업이다. 무턱대고 중복부터 하면 정합성 붕괴가 발생한다.

## 연결 개념
- **정규화 (Normalization)**: 반정규화의 전제 조건.
- **조인 (Join)**: 반정규화를 통해 제거하고자 하는 대상.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 조회 성능(Read) 향상을 위해 데이터 정합성(Write)과 저장 공간을 포기하는 의도적 중복 설계
> 2. **가치**: 복잡한 다중 조인을 제거하여 디스크 I/O를 줄이고 대용량 쿼리 응답 속도를 개선
> 3. **판단 포인트**: 반정규화 적용 전 뷰(View), 인덱스 조정, 애플리케이션 캐싱 등 대안을 선행 검토

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 반정규화의 필요성과 정규화 트레이드오프 이해 | 테이블/컬럼/관계 병합 및 분할, 정합성 훼손 리스크 | 반정규화를 정규화 이전 단계로 오해하는 서술 |

> 요약: 정규화 완료 후 성능 한계 극복을 위해 신중하게 접근하는 물리적 설계 과정임을 강조한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 시스템 성능 향상을 위해 정규화된 데이터 모델에 테이블 병합, 분할, 컬럼 중복 등을 적용하는 물리적 모델링 기법
- 배경: 높은 정규화 차수는 다중 조인을 유발하여 대용량 트랜잭션 환경에서 디스크 I/O 병목 및 조회 지연 초래
- 필요성: 조인 경로 단축 및 집계 연산 사전 처리를 통한 읽기(Read) 성능 극대화 요구 (응답시간 SLA 충족)

---

## Ⅱ. 구조 및 구성요소

```text
논리적 정규화 모델 -> 성능 진단/평가 -> 반정규화 대상 식별 -> 기법 적용 -> 물리적 반정규화 모델
                       |                                         |
                       +-> 인덱스/캐시 대안 우선 검토            +-> 정합성 유지 트리거/배치 설계
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 테이블 반정규화 | 1:1, 1:M 관계 테이블 병합 또는 이력 테이블 분할 | 수직 분할, 수평 분할 포함 |
| 컬럼 반정규화 | 자주 조회되는 컬럼 중복 저장, 파생/요약 컬럼 추가 | 정합성 깨짐 위험 가장 큼 |
| 관계 반정규화 | 조인 경로 단축을 위해 중복 관계 추가 | 데이터 중복 없이 관계만 추가 |

> 요약: 테이블, 컬럼, 관계 측면에서 중복을 허용하여 조인 비용을 최소화하고 조회 효율을 극대화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
정규화 완료 -> 대안 검토(인덱스/캐시) -> 대상 식별(빈도/크기) -> 반정규화 적용 -> 정합성 보장 장치 마련
```

- 1단계 정규화 및 진단: 3NF 이상의 논리 데이터 모델 구축 및 조회 빈도, 데이터 량, 조인 복잡도 분석
- 2단계 대안 검토: 뷰(View), 클러스터드 인덱스 조정, 애플리케이션 캐싱 등 중복 없는 성능 개선책 확인
- 3단계 기법 적용: 병합, 분할, 중복 등 구체적인 반정규화 기법을 물리 모델에 반영
- 4단계 사후 통제: 트리거(Trigger) 또는 애플리케이션 로직을 통해 중복 데이터 간 정합성 동기화

> 요약: 철저한 대안 검토 후 적용하며, 반드시 정합성 동기화 방안을 함께 설계한다.

---

## Ⅳ. 특징
- 조회 성능 향상: 디스크 I/O 감소 및 다중 조인 회피를 통한 빠른 쿼리 응답 (Read 성능 극대화)
- 갱신 이상 위험: 단일 논리 데이터가 여러 곳에 저장되어 갱신 시 누락/불일치 위험 존재
- 쓰기 성능 저하: 한 번의 갱신으로 여러 중복 데이터를 동시 수정해야 하므로 트랜잭션 비용 증가
- 관리 복잡도 증가: 데이터 무결성을 유지하기 위한 애플리케이션 로직이나 DB 트리거 유지보수 부담

> 요약: 읽기 속도를 얻는 대신 쓰기 속도 저하와 데이터 정합성 관리 비용을 지불하는 트레이드오프 기법이다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 정규화 (Normalization) | 반정규화 (Denormalization) | 선택 기준 |
|:---|:---|:---|:---|
| 주요 목적 | 데이터 정합성, 중복 제거 | 조회 성능 향상, 복잡도 완화 | 시스템 워크로드 |
| 적용 단계 | 논리 데이터 모델링 단계 | 물리 데이터 모델링 단계 | 모델링 진행 절차 |
| 이상 현상 | 억제됨 (발생 가능성 최소화) | 발생 위험 높음 (추가 통제 필요) | 데이터 신뢰성 요구 |

> 요약: 쓰기 트랜잭션이 많은 OLTP는 정규화를 우선하고, 읽기/집계가 많은 DW/OLAP은 반정규화를 적극 활용한다.

**리스크·대응:**
- 정합성 훼손: 중복 데이터 갱신 누락 → DB 트리거 또는 트랜잭션 단위 묶음 처리 (지표: 무결성 위배 건수)
- 스토리지 낭비: 무분별한 중복으로 용량 증가 → 접근 빈도 기반 비용-편익 분석(CBAM) 수행 후 적용 (지표: 스토리지 사용률)

**도입 후 점검 지표:**
- 성능/효율: 목표 쿼리 응답 시간 1초 이내 달성 — APM 슬로우 쿼리 모니터링
- 품질/운영: 중복 데이터 간 불일치 0건 — 데이터 정합성 검증 배치 스크립트 실행

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 이력/통계 테이블 사전 집계 적용: 배치 프로세스를 통해 월별 요약 테이블을 별도 생성하여 실시간 집계 연산 부하 제거
2. CQRS 패턴 분리: 쓰기 모델(정규화 유지)과 읽기 모델(반정규화/NoSQL)을 분리하고 이벤트 브로커로 동기화 처리
3. 인메모리 캐시(Redis) 우선 검토: RDB의 반정규화를 최소화하고, 자주 조회되는 조인 결과는 Redis에 캐싱

**결론:**
- 기술사 판단: 조인 부하가 심각하더라도 즉각적인 반정규화보다는 인덱스 튜닝과 캐시 도입을 선행해야 하며, 최종 수단으로 제한적 적용이 필요하다.
- 향후 방향: 마이크로서비스(MSA) 환경에서는 분산 DB 간의 물리적 조인이 불가능하므로, API 컴포지션 및 CQRS 기반의 논리적 반정규화 설계가 중요해진다.
