## 미리 알고가기

- 반정규화는 조회 성능과 단순화를 위해 일부 중복을 의도적으로 허용하는 설계임
- 정규화의 반대가 아니라 워크로드 기반 최적화 수단임
- 무결성 저하 위험을 통제할 보완 장치가 필요함

## Ⅰ. 개요

- **정의/개념**: 반정규화는 조인 비용과 집계 지연을 줄이기 위해 정규화된 스키마 일부를 통합하거나 중복 컬럼과 요약 테이블을 도입해 조회 성능과 사용 편의성을 높이는 물리 설계 최적화 기법임
- **배경/필요성**: 대량 조회와 실시간 화면 응답이 중요한 시스템에서는 정규화만으로 성능 요구를 만족하기 어려우므로, 허용 가능한 범위의 중복을 전략적으로 활용할 필요가 있음

## Ⅱ. 특징

- 조인 수를 줄여 조회 지연을 낮출 수 있음
- 요약 데이터와 캐시성 속성을 미리 보유해 읽기 효율을 높임
- 갱신 경로가 늘어 무결성 유지가 어려워질 수 있음
- 반정규화는 명확한 워크로드 근거가 있을 때만 정당화됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규화 | 반정규화 |
|:---|:---|:---|
| 중복 수준 | 최소화 | 의도적 허용 |
| 강점 | 무결성과 관리 용이 | 조회 성능과 단순 질의 |
| 한계 | 조인 비용 증가 가능 | 갱신 복잡도와 불일치 위험 |
| 적합 환경 | 트랜잭션 정합성 중심 | 읽기 중심 고성능 요구 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Target Query Analysis | 병목 조회와 집계를 식별해 어떤 중복이 필요한지 결정함 |
| Denormalized Attribute or Table | 자주 함께 쓰는 데이터를 합쳐 조인 비용을 줄임 |
| Sync Mechanism | 트리거와 배치와 애플리케이션 로직으로 중복 데이터 일관성을 유지함 |
| Validation Metric | 성능 개선과 무결성 손실을 함께 측정해 반정규화 효과를 검증함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 병목 조회 분석  | --> | 중복 구조 설계  | --> | 동기화 구현    | --> | 성능/정합 검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **병목 조회 분석**: 느린 질의와 집계 패턴을 확인함
2. **중복 구조 설계**: 합칠 컬럼과 요약 테이블을 결정함
3. **동기화 구현**: 갱신 시 중복 데이터를 함께 맞춤
4. **성능과 정합 검증**: 응답 시간과 불일치를 함께 측정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 병목 분석 없이 반정규화를 적용하면 복잡도만 증가하고 실제 성능 개선이 미미할 수 있음
   - 해결방안: query hotspot 기반으로 대상을 선정하고 latency improvement ratio와 unused denormalized field count로 검증함
2. 문제: 동기화 경로가 누락되면 중복 데이터 불일치가 운영 오류로 직결될 수 있음
   - 해결방안: sync contract와 reconciliation job을 운영하고 inconsistency incident count와 sync lag로 검증함
3. 문제: 반정규화 구조가 늘어나도 정리 기준이 없으면 장기적으로 데이터 모델 이해도가 급격히 떨어질 수 있음
   - 해결방안: design rationale를 문서화하고 schema complexity score와 maintenance effort trend로 검증함

## Ⅶ. 적용 사례

- 대시보드 조회 DB에서는 병목 질의를 기준으로 반정규화를 적용하고 확인 지표는 latency improvement ratio와 unused denormalized field count임
- 주문 집계 시스템에서는 동기화 계약을 운영하고 확인 지표는 inconsistency incident count와 sync lag임
- 장기 운영 SaaS에서는 설계 근거를 문서화하고 확인 지표는 schema complexity score와 maintenance effort trend임

## Ⅷ. 결론

반정규화는 무결성을 포기하는 편법이 아니라 조회 성능 이득이 중복 관리 비용을 명확히 상회할 때 선택하는 설계 trade-off임.
