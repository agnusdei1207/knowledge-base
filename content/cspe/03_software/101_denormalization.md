## 미리 알고가기

- 반정규화는 조회 성능을 높이기 위해 중복 컬럼이나 요약 테이블을 의도적으로 두는 설계임
- 정규화가 틀렸다는 뜻이 아니라 조회 병목이 분명할 때 추가로 적용하는 물리 설계 기법임
- 중복이 늘어나는 만큼 동기화 경로와 검증 절차를 함께 설계해야 함

## Ⅰ. 개요

- **정의/개념**: 반정규화는 정규화된 스키마에 중복 컬럼이나 요약 테이블이나 통합 테이블을 추가해 조인 수와 집계 비용을 줄이고 조회 응답을 빠르게 만드는 물리 설계 최적화 기법임.
- **배경/필요성**: 대시보드와 목록 화면처럼 같은 조회가 반복되는 시스템에서는 논리적으로 올바른 구조만으로는 응답 시간을 맞추기 어려우므로, 통제 가능한 범위에서 중복을 활용할 필요가 있음.

## Ⅱ. 특징

- 조인 수와 집계 비용을 줄여 반복 조회를 빠르게 만들 수 있음
- 화면에 자주 함께 쓰이는 데이터를 한 번에 가져오게 해 질의를 단순하게 만들 수 있음
- 같은 사실을 여러 곳에 저장하므로 갱신 누락과 불일치 위험이 커짐
- 병목 질의가 분명할 때만 적용해야 하며 관성적으로 넓히면 관리 비용이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 정규화 | 반정규화 |
|:---|:---|:---|
| 데이터 중복 | 같은 사실을 한 곳에 두려고 함 | 조회 성능을 위해 같은 사실을 여러 곳에 둘 수 있음 |
| 강점 | 무결성과 변경 관리가 쉬움 | 조인과 집계가 줄어 조회가 빨라짐 |
| 한계 | 조회가 복잡해질 수 있음 | 갱신 경로가 늘어 불일치가 생기기 쉬움 |
| 적합 환경 | 트랜잭션 정합성이 우선인 업무 | 읽기 비중이 높고 응답 시간이 중요한 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 병목 질의 분석 | 느린 조회와 집계를 찾아 어떤 중복이 실제로 필요한지 정함 |
| 중복 컬럼 또는 요약 테이블 | 자주 함께 읽는 값을 미리 모아 조인과 집계 비용을 줄임 |
| 동기화 경로 | 트리거와 배치와 애플리케이션 로직으로 원본과 중복 데이터를 함께 맞춤 |
| 검증 지표 | 응답 시간 개선과 데이터 불일치 발생 여부를 함께 측정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 병목 조회 분석  | --> | 중복 구조 설계  | --> | 동기화 구현    | --> | 성능/정합 검증  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **병목 조회 분석**: 느린 질의와 반복 집계가 어디서 발생하는지 확인함
2. **중복 구조 설계**: 어떤 컬럼과 어떤 요약 결과를 미리 둘지 정함
3. **동기화 구현**: 원본 데이터가 바뀔 때 중복 데이터도 함께 갱신함
4. **성능과 정합 검증**: 응답 시간과 불일치 건수를 함께 점검함

## Ⅵ. 실무 적용 및 유의점

1. 대시보드와 조회 인터페이스처럼 같은 조인과 집계가 반복되는 환경에서는 반정규화가 효과적이지만 동기화 경로가 빠지면 바로 불일치가 생기므로 원본과 중복 데이터의 갱신 계약을 두고 응답 시간 개선율과 동기화 지연 시간으로 확인함.
2. 핵심 트랜잭션 테이블에 근거 없이 반정규화를 넓히면 쓰기 복잡도만 커지므로 병목 질의가 있는 부분에만 제한해 적용하고 중복 컬럼 사용률과 데이터 불일치 건수로 확인함.

## Ⅶ. 결론

반정규화는 정규화를 버리는 편법이 아니라 조회 성능 이득이 중복 관리 비용보다 클 때 제한적으로 쓰는 물리 설계 선택임.
