## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 컴퓨터와 외부 장치 간 데이터 교환을 관리하고 제어하는 OS 하위 시스템 |
| 필요성 | 장치 간 속도 차이 극복, 독립적인 장치 제어 및 CPU 개입 최소화 |
| 출제 의도 | 제어 방식(Polling, Interrupt, DMA), 버퍼링/스풀링 개념 이해 |

## Ⅱ. 구성요소
```text
[ CPU ] <---(Intr)--- [ I/O Controller ] <---> [ Device ]
  |                       |
  +-------(Bus)-----------+--- [ DMA Controller ] --- [ Memory ]
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 장치 드라이버 | 하드웨어 특정 기능을 OS가 사용할 수 있게 추상화 | 기기 매뉴얼/통역사 |
| 버퍼링 (Buffering) | 전송 속도 차이를 완충하기 위해 임시 저장소 활용 | 댐/저수지 |
| DMA | CPU 도움 없이 I/O 장치와 메모리 간 직접 데이터 전송 | 전담 운송팀 |
> 요약: CPU는 I/O 시작만 명령하고, 완료 시 인터럽트로 결과를 보고받음.

## Ⅲ. 절차
```text
App I/O Call -> Kernel Driver -> Device Cmd -> [Data Transfer] -> Intr
                                                      |           |
                          (Buffer Fill/Empty) <-------+           v
                                                            Update Status
```
1. I/O 요청: 응용 프로그램이 커널에 읽기/쓰기 시스템 콜 호출.
2. 드라이버 작동: 커널이 해당 장치 제어기에 명령 전달 및 작업 개시.
3. 데이터 전송: 버퍼를 활용해 데이터 이동 (DMA 방식 시 CPU 유휴).
4. 완료 통보: 작업 종료 후 장치 제어기가 CPU에 인터럽트 발생 및 앱 재개.
> 요약: 버퍼링과 인터럽트 기반 처리를 통해 CPU의 자원 활용도를 높임.

## Ⅳ. 문제점
- 대량의 작은 I/O 요청 발생 시 잦은 인터럽트로 인한 CPU 컨텍스트 스위칭 과부하.
- 버퍼 오버런/언더런 발생 시 데이터 유실 또는 전송 중단 위험.

## Ⅴ. 개선방안
- Interrupt Coalescing 기술을 통해 여러 인터럽트를 하나로 묶어 처리.
- 이중 버퍼링(Double Buffering) 또는 순환 버퍼링 적용으로 데이터 흐름 연속성 확보.

## Ⅵ. 전망
- I/O Virtualization: SR-IOV 등을 통한 가상머신별 독립적/고속 I/O 할당 확대.
- SmartNIC/DPU: 네트워크 및 스토리지 I/O를 전용 프로세서가 처리하여 CPU 부하 0화.
