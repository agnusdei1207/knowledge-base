## Ⅰ. 개요
- 소프트웨어 내부 로직과 코드 구조를 기반으로 수행하는 화이트박스 테스팅 기법임
- 코드의 실행 경로를 분석하여 테스트 케이스의 충분성(Coverage)을 측정함
| 구분 | 내용 | 비유 |
| --- | --- | --- |
| 출제의도 | 제어 흐름 vs 데이터 흐름, 커버리지 유형(문장/분기/조건/MC/DC) | 건물 배선도 점검 |

## Ⅱ. 구성요소
- 제어 흐름 그래프(CFG)와 데이터 흐름 분석으로 구성됨
[분기/조건] --(제어 흐름)--> [경로 실행]
[정의/사용] --(데이터 흐름)--> [값 변동]
- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 제어 흐름 테스팅 | 조건문, 반복문 등 프로그램의 실행 순서 검증 | 미로 탈출 경로 |
| 데이터 흐름 테스팅 | 변수의 정의(Definition)와 사용(Usage) 관계 분석 | 택배물 추적 |
| 커버리지(Coverage) | 테스트에 의해 실행된 범위의 정량적 비율 | 지도 도달 범위 |
> 요약: 제어 경로와 변수의 정의·사용 관계를 기준으로 테스트 대상을 선정함

## Ⅲ. 절차
- 로직 분석 기반의 테스트 설계 및 실행 절차임
[소스 분석] -> [그래프 모델링] -> [경로 선정] -> [TC 실행 및 측정]
- 4단계 설명
1) CFG 생성: 소스코드를 노드와 에지로 구성된 흐름도로 변환함
2) 커버리지 목표 설정: 프로젝트 중요도에 따라 분기/조건 등 목표 확정함
3) 테스트 데이터 생성: 선정된 경로를 통과하기 위한 입력값 도출함
4) 커버리지 리포팅: 도구를 통해 실제 실행된 코드 비율을 산출함
> 요약: 목표 커버리지와 실제 실행 비율을 비교하여 미실행 구조를 식별함

## Ⅳ. 문제점
- 분기와 반복문이 늘어나면 실행 경로 수가 증가하여 전체 경로 테스트가 어려움
- 높은 커버리지가 반드시 높은 품질(요구사항 만족)을 보장하지 않음 (원인: 설계 누락 미감지)

## Ⅴ. 개선방안
- (단기) 리스크가 높은 핵심 모듈에 대해 MC/DC 수준의 강화된 커버리지 적용함
- (중기) 변이 테스팅(Mutation Testing)을 병행하여 테스트 케이스의 유효성 검증함
- (장기) 자동 테스트 데이터 생성 도구(Symbolic Execution 등)를 통한 효율화함

## Ⅵ. 전망
- 고신뢰 시스템(차량, 항공 등)에서는 국제 표준(ISO 26262 등)에 따른 구조적 테스팅이 필수임
- 향후 AI 모델의 내부 뉴런 활성화 분석 등 'AI 화이트박스 테스팅' 영역으로 확장될 것임
