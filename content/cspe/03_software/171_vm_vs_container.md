## 미리 알고가기

- 하이퍼바이저는 물리 자원을 분할해 각각 독립 운영체제를 실행하는 VM을 제공함
- 게스트 OS는 VM 안에서 독립 커널·드라이버·시스템 서비스를 실행함
- 컨테이너는 호스트 커널을 공유하고 애플리케이션 프로세스의 가시 범위와 자원을 분리함
- VM 이미지는 운영체제를 포함하고 컨테이너 이미지는 앱·런타임·사용자 공간 라이브러리를 포함함
- 격리 경계는 한 워크로드의 권한·결함이 호스트나 다른 워크로드에 미치는 범위를 정함
- 컨테이너를 VM 안에서 실행하면 VM의 커널 경계와 컨테이너의 배포 단위를 함께 사용할 수 있음
- 네임스페이스는 자원 가시 범위를 분리하고 cgroup은 CPU·메모리 사용량을 제한함

## 작성 근거(검토용)

- VM과 컨테이너는 가상화 대상과 커널 공유 여부가 모든 차이의 원인이므로 이를 첫 비교축으로 둠
- 가상화 구조·실행 비용·적합 조건의 정확히 3개 축을 구조와 사례에서 회수함
- Ⅴ절은 격리·운영 요구 분석부터 실행 단위 선택과 검증까지의 의사결정 절차로 구성함
- 제목부터 결론까지 5회 전수 검수하여 장점 표현을 구조적 원인과 측정 지표로 교정함

## Ⅰ. 개요

- **정의/개념**: VM은 하드웨어를 가상화해 게스트 OS를 실행하고 컨테이너는 운영체제 커널을 공유해 애플리케이션 프로세스를 격리함
- **배경/필요성**: 워크로드별 격리 수준과 배포 밀도를 맞추기 위해 커널 경계·자원 비용·실행 단위의 비교가 필요함

### 쉽게 이해하기 (학습용)
- VM은 운영체제 단위, 컨테이너는 같은 커널 위의 프로세스 단위로 실행 환경을 분리함

## Ⅱ. 특징

- VM은 워크로드마다 독립 커널을 사용해 운영체제 종류와 패치 주기를 분리함
- 컨테이너는 호스트 커널을 공유해 앱과 사용자 공간 의존성만 이미지로 배포함
- VM은 부팅 단계와 게스트 OS 메모리가 필요하고 컨테이너는 주 프로세스 시작이 실행 기준임
- 두 기술은 대체 관계만이 아니며 클라우드에서는 VM 위에 컨테이너 노드를 구성할 수 있음

### 쉽게 이해하기 (학습용)
- VM은 더 독립적인 경계를, 컨테이너는 빠른 배포와 높은 실행 밀도를 제공하며 함께 사용할 수도 있음

## Ⅲ. 핵심 비교

| 판단 기준 | VM | 컨테이너 |
|:---|:---|:---|
| 가상화 구조 | 가상 하드웨어 위에 VM별 게스트 커널 실행 | 네임스페이스·cgroup으로 분리하되 호스트 커널 공유 |
| 실행 비용 | 운영체제를 포함한 이미지와 부팅·게스트 자원 필요 | 앱·런타임 이미지와 주 프로세스 중심 자원 필요 |
| 적합 조건 | 다른 OS·커널 또는 독립 커널 격리 필요 | 동일 커널에서 빠른 이미지 배포·높은 실행 밀도 필요 |

> 요약: VM은 독립 커널 경계, 컨테이너는 공유 커널 위의 프로세스 격리가 중심임.

### 쉽게 이해하기 (학습용)
- VM은 집을 통째로 분리하고 컨테이너는 한 건물 안의 공간을 커널 규칙으로 나누는 방식에 가까움

## Ⅳ. 구성요소 및 구조

| 계층 | VM 구조 | 컨테이너 구조 |
|:---|:---|:---|
| 물리 자원 | 하이퍼바이저가 VM별 가상 하드웨어를 할당함 | 호스트 OS가 컨테이너 프로세스에 자원을 할당함 |
| 운영체제 | VM마다 게스트 OS와 커널을 실행함 | 모든 컨테이너가 호스트 커널을 공유함 |
| 격리 계층 | 가상 CPU·메모리·장치와 VM 경계 | 네임스페이스·cgroup·커널 권한 경계 |
| 실행 단위 | 게스트 OS 안의 애플리케이션 | 이미지에서 시작한 주 프로세스 |
| 영속 저장 | 가상 디스크와 외부 블록·파일 스토리지 | 볼륨과 외부 블록·파일 스토리지 |

```text
VM:         하드웨어 -> 하이퍼바이저 -> 게스트 OS -> 애플리케이션
컨테이너:  하드웨어 -> 호스트 OS ----> 컨테이너 -> 애플리케이션
```

> 요약: VM은 게스트 OS 단위로, 컨테이너는 호스트 커널을 공유하는 프로세스 단위로 실행됨.

### 쉽게 이해하기 (학습용)
- VM에는 게스트 운영체제가 반복되고 컨테이너에는 애플리케이션 실행 계층이 반복됨

## Ⅴ. 원리 및 절차 흐름도

```text
격리·OS 요구 분석 -> 실행 비용·배포 단위 비교 -> VM·컨테이너 선택 -> 보안·자원 설정 -> 성능·복구 검증
```

1. 독립 커널·다른 운영체제·규제 격리가 필요한지 확인함
2. 시작 시간·이미지 크기·노드당 실행 수와 배포 단위를 비교함
3. VM·컨테이너 또는 VM 위 컨테이너의 결합 구조를 선택함
4. 가상 하드웨어나 네임스페이스·cgroup·권한 경계를 설정함
5. 격리 실패 범위·시작 시간·자원 사용량·복구 시간을 측정함

> 요약: 필요한 커널 격리와 실행 비용을 대조해 실행 단위를 고르고 실제 운영 지표로 검증함.

### 쉽게 이해하기 (학습용)
- 얼마나 단단히 분리할지와 얼마나 가볍게 배포할지를 먼저 정한 뒤 구조를 선택함

## Ⅵ. 실무 사례

1. 상용 패키지는 VM으로 게스트 OS를 분리하고 부팅시간·VM당 메모리 사용량을 확인함
2. 무상태 API는 컨테이너 이미지로 배포하고 시작시간·노드당 실행 수를 확인함

### 쉽게 이해하기 (학습용)
- 독립 커널이 필요한 시스템은 VM, 빠른 수평 확장이 필요한 API는 컨테이너가 적합할 수 있음

## Ⅶ. 결론

- VM과 컨테이너는 필요한 커널 격리 수준과 배포 단위·자원 비용을 기준으로 선택해야 함

### 쉽게 이해하기 (학습용)
- 어느 기술이 항상 우수한 것이 아니라 격리 경계와 운영 비용이 업무 조건에 맞아야 함
