## Ⅰ. 개요
- 정의: LLM Code Generation의 핵심 개념과 주요 목적
- 배경: 소프트웨어 복잡도 증가 및 품질 보증 요구 증대
- 출제 의도: | 유형 | 난이도 | 중요도 |
| --- | --- | --- |
| 기술 비교 | 중 | 상 |

## Ⅱ. 구성요소
- ASCII 구조도
  [Prompt] -> [ LLM (GPT/Claude) ] -> [ Source Code ]
                (Transformer)

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 프롬프트 엔지니어링 | AI에 명확한 지시를 내리는 기술 | 질문의 기술 |
| 컨텍스트 윈도우 | AI가 한 번에 이해하는 정보량 범위 | 기억력 용량 |
| 할루시네이션 | 그럴듯하지만 틀린 코드를 생성하는 현상 | 환각 현상 |

> 요약: 대규모 언어 모델을 활용한 소스 코드 자동 생성 기술임.

## Ⅲ. 절차
- ASCII 흐름도
  Problem Define -> Prompting -> Gen Code -> Review -> Refine

1. 문제 정의: 개발하고자 하는 기능의 상세 요건 기술함.
2. 프롬프트 작성: 역할 부여, 제약 조건, 예시(Few-shot) 포함함.
3. 코드 생성 및 검토: 생성된 코드의 논리 및 보안성 검증함.
4. 반복 수정: 피드백을 통해 코드를 보완하고 최적화함.

> 요약: 개발 속도의 획기적 단축과 단순 반복 코딩의 제거임.

## Ⅳ. 문제점
- 훈련 데이터의 편향성으로 인한 비효율적 코드 생성 가능함.
- 민감한 기업 내부 코드의 외부 유출 보안 리스크 존재함.

## Ⅴ. 개선방안
- 기업 전용(Private) LLM 구축 및 데이터 마스킹 기술 적용함.
- 생성 코드에 대한 자동화된 유닛 테스트 및 보안 스캔 연동함.

## Ⅵ. 전망
- 코딩 언어 장벽이 사라지고 설계 중심의 개발 문화로 전이됨.
- CSF: 명확한 요구사항 정의 능력과 AI 결과물에 대한 비판적 수용임.
