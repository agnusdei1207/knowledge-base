## Ⅰ. 개요
- **정의**: 중간 표현(IR)을 타깃 기계의 목적 코드로 변환하는 컴파일러 후단 단계
- **배경/필요성**: 고수준 언어와 하드웨어 사이의 의미 격차를 해소하여 실행 가능한 바이너리를 산출해야 하므로 체계적 코드 생성이 필요함
- **비유**: 설계 도면(IR)을 실제 건축 자재(명령어)로 변환하는 시공 과정과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 코드 생성기의 역할과 구성 이해 | 명령어 선택·레지스터 할당·명령어 스케줄링 3대 과제 | 코드 최적화(181 참조)와 코드 생성 단계의 차이 구분 |

> 요약: IR을 타깃 머신 명령어로 정확히 변환하는 컴파일러 후단 핵심 단계임

## Ⅱ. 구성요소
```text
IR Input
    |
    v
+---------------------+
| Instruction Select  |
+---------------------+
    |
    v
+---------------------+
| Register Allocate   |
+---------------------+
    |
    v
+---------------------+
| Instruction Sched   |
+---------------------+
    |
    v
Target Machine Code
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 명령어 선택 | IR 연산을 타깃 ISA 명령어로 매핑 | 레시피를 현지 재료로 대체 |
| 레지스터 할당 | 가상 레지스터를 물리 레지스터에 배정, 부족 시 스필 처리 | 제한된 책상 위 공간에 서류 배치 |
| 명령어 스케줄링 | 파이프라인 스톨 최소화를 위해 명령어 순서 재배치 | 공장 컨베이어에서 병목 없이 작업 순서 조정 |

> 요약: 선택-할당-스케줄링 3단계로 IR을 효율적 기계어로 변환함

## Ⅲ. 절차
```text
IR --> 트리/DAG 패턴 매칭 --> 레지스터 그래프 착색 --> 순서 재배치 --> 목적 코드 출력
```
- 1단계: IR을 트리 또는 DAG 형태로 분해하여 타깃 명령어 패턴과 매칭
- 2단계: 간섭 그래프 구성 후 그래프 착색 알고리즘으로 레지스터 할당
- 3단계: 데이터 의존성·지연 시간을 고려하여 명령어 실행 순서 재배치
- 4단계: 최종 기계어 인코딩 및 재배치 정보 포함한 오브젝트 파일 출력

> 요약: 패턴 매칭-그래프 착색-스케줄링-인코딩 순서로 목적 코드를 산출함

## Ⅳ. 문제점
- NP-난해 조합 문제: 명령어 선택·레지스터 할당이 NP-완전 문제여서 최적해 산출 곤란 — 휴리스틱 의존
- 타깃 이식성 부족: ISA별 코드 생성기를 별도 구현해야 함 — 다중 아키텍처 지원 비용 증가
- 코드 품질 편차: 휴리스틱 선택에 따라 동일 IR에서 성능 차이 발생 — 예측 가능성 저하

> 요약: 조합 복잡도·이식성·품질 편차가 코드 생성의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 탐색 기반 슈퍼옵티마이저로 소규모 코드 시퀀스의 최적해 도출
2. 중기: LLVM 등 타깃 독립 백엔드 프레임워크 활용으로 다중 ISA 코드 생성기 재사용
3. 장기: ML 기반 비용 모델 학습으로 명령어 선택·스케줄링 품질 균일화

> 요약: 슈퍼옵티마이저·공통 백엔드·ML 비용 모델로 코드 생성 품질을 개선함

## Ⅵ. 전망
- 발전 방향: RISC-V 등 신규 ISA 확산에 따른 코드 생성기 자동 합성 기술 부상
- 기술사적 판단: 이기종 컴퓨팅(CPU+GPU+NPU) 환경에서 통합 코드 생성 파이프라인의 필요성 증가
- 기술사 제언: 타깃 독립 IR 설계와 자동화된 백엔드 생성을 병행하여 이식성과 성능을 동시 확보해야 함
