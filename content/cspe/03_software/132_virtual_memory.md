## Ⅰ. 개요
| 구분 | 내용 |
|---|---|
| 정의 | 물리 메모리보다 큰 프로세스를 실행하기 위해 보조기억장치를 활용하는 기법 |
| 필요성 | 한정된 물리 RAM 극복, 다중 프로그래밍 효율 극대화, 메모리 보호 |
| 출제 의도 | 페이징(고정 크기) vs 세그멘테이션(가변/논리 크기) 비교 역량 |

## Ⅱ. 구성요소
```text
[ Logical Address ]    [ Page Table ]    [ Physical Address ]
+--------------+       +-----------+      +--------------+
| Page Number  | ----> | Frame Num | ---> | Frame Number |
+--------------+       +-----------+      +--------------+
| Offset       | -----------------------> | Offset       |
+--------------+                          +--------------+
```
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 페이징 | 고정 크기의 페이지로 나누어 관리 | 규격화된 박스 보관 |
| 세그멘테이션 | 논리적 단위(Code/Data/Stack)로 관리 | 물건 크기별 맞춤 보관 |
| TLB | 주소 변환 속도 향상을 위한 고속 캐시 | 빠른 찾기 색인 |
> 요약: 페이징은 내부 단편화, 세그멘테이션은 외부 단편화 발생 가능성이 있음.

## Ⅲ. 절차
```text
CPU Logical Addr -> MMU Check -> TLB Hit? --(No)--> Page Table Walk
                         |        | (Yes)              |
                         +--------+----------> Physical Addr Access
```
1. 논리 주소 생성: CPU가 프로그램 실행 중 가상 주소를 참조.
2. TLB 참조: 고속 캐시인 TLB에서 물리 주소 변환 정보 확인.
3. 페이지 테이블 참조: TLB Miss 시 메모리의 페이지 테이블에서 매핑 정보 추출.
4. 물리 주소 접근: 변환된 실제 주소로 메모리 데이터 로드/저치.
> 요약: MMU 하드웨어를 통해 실시간으로 가상 주소를 물리 주소로 매핑함.

## Ⅳ. 문제점
- 페이징 시 페이지 테이블 크기 비대화로 인한 메모리 점유 및 관리 부담.
- 가상 메모리 활용 시 디스크 I/O 빈번으로 인한 스래싱(Thrashing) 위험.

## Ⅴ. 개선방안
- 다단계 페이지 테이블(Multi-level) 또는 역 페이지 테이블 적용으로 크기 축소.
- 워킹 셋(Working Set) 모델 및 PFF(Page Fault Frequency) 알고리즘으로 스래싱 방지.

## Ⅵ. 전망
- 대용량 페이지(Huge Pages): 1GB 이상의 페이지 단위 지원을 통한 변환 오버헤드 축소.
- 보안 강화: Enclave 기반 가상 메모리 보호 및 하드웨어 암호화 기술 통합.
